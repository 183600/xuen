# 第 4 轮（灵感驱动研究循环·新灵感三元组第 1 轮；本轮灵感：「SLAM」×「迭代验证」）

> **基线**：第 3 轮产出 MetricVoiceGauge-NCD-HUTDH-v21+IP-425–430（SDC/CAC/DCL/GIC/HPC+/CFC+ 语义-合规层；其上承 v20 联邦感知证书 PCA/CTS/CFC/HPC、v19 DCM/OGCC/CCV/DRS/OGC、v17 CLP/S2C/HCG/PSV/APS/AMC）。
> 本轮纪律：**证书不是绝对世界里的静态真值，而是"在某个位姿框架下签发、随漂移贬值、可被闭环修正与反例推翻的可证伪假设"**。不推倒 v21：SDC/CAC/DCL/GIC/HPC+/CFC+ 全部保留，v20/v19/v17 全部保留。本轮只做一件事：**给 v21 的证书装上"坐标系"与"证伪回路"——把几何安全升级为框架一致、持续可验证的证书体系，并顺手封堵 v21 最大风险（κ_c 静态经验假设 + E798 监控缺乏统计合法性）**。

## 0. 直觉与动机

**灵感 1（SLAM → 证书的坐标系、漂移与闭环一致性）**
直觉：v21 把证书当成"在一个静止、精确已知的世界坐标系里"签发的。但真实机器人一边走一边建图，位姿有漂移。一个完美的检测器，如果位姿错了，CertBox 会落到错误位置——轻则凭空造出假障碍（活性损失），重则更可怕：**把真实障碍"挪走"，在真实位置留下假自由空间**。SLAM 的核心教训是：**一切几何量都相对于某个位姿估计，误差随路径累积，只有闭环才能全局校正**。所以每张证书都必须携带"框架标签 + 位姿协方差 + 漂移上界"，全局复用前按位姿不确定性膨胀；闭环发生时全局位姿被修正，此前签发的证书可能瞬间失效，必须触发重新验证或失效回退，而不是继续沿用旧框架的结论。核心创新：**框架标签证书 (Frame-Tagged Certificate, FTC) + 证书位姿图与闭环重校 (Certificate Pose Graph with Loop-Closure Reconciliation, CPG-LCR)**。

关键反直觉点 1：v21 的"跨机器人 NMS 去重"在帧未对齐时是**错的**。相对位姿有协方差时，两台机器人报的"同一框"可能是不同物体（漏合并→重复证据），也可能是同一物体的两次观测被漂移拉开而误当独立证据（假独立票→击穿 CFC+ 的模态多样性）。安全方向是**双向不对称**的：**障碍证据取并（宁多勿少），投票去重取"只要存在一种对齐使其可能同源即合并为一票"（宁少勿多）**。这把 v21 用来封堵风险的模块，变成一个必须重新设计的风险源。

关键反直觉点 2：位姿不确定性不仅影响障碍，也影响缺席证书。AbsCert 说"区域 Cov 内无人"，但 Cov 本身是在漂移框架里算的；闭环一修正，Cov 可能整体平移，原本"覆盖区内"的人可能落到覆盖区外（或反之）。缺席证书的可靠性界里必须乘上框架可靠项：`P(absent) ≥ 1 - δ_abs - δ_frame`。

**灵感 2（迭代验证 → 证书是可证伪假设，验证必须 anytime-valid 且独立）**
直觉：v21 最大的风险是 κ_c 是经验假设，且 E798 的"在线监控"没有统计合法性——你可以在任意时刻停下来宣布"κ 达标"，这正是 optional stopping / p-hacking。迭代验证的正确做法：把 κ 当作一个**持续被检验的假设**，用 **anytime-valid 置信序列（e-process + Ville 不等式）**维护一个在任意停时都有效的召回率下界 κ̂⁻_t(α)。每当证书被"打脸"（在 AbsCert 声称无人的区域后来检出人），记一次 **falsification event**，更新 κ̂⁻ 并**追溯性地使依赖该证书的决策失效**（审计链留痕）。更进一步：没有全量真值时，用**双通道捕获-再捕获 (Capture-Recapture)** 估计漏检数，从而估计召回。核心创新：**任意停时有效召回监控 (Anytime-Valid Recall Monitor, AVRM) + 跨通道捕获-再捕获估计 (Cross-Channel Capture-Recapture Estimator, CCRE) + 反例账本与追溯失效 (Falsification Ledger & Retroactive Invalidation, FLRI)**。

关键反直觉点 3（最深）：**验证信号本身可能被同一个失效模式蒙蔽**。如果你从未检出那个人（正是漏检），你永远不会记录这次 falsification——验证循环继承了被验证系统的盲区（survivorship / unobservable falsification）。capture-recapture 的估计依赖两通道**条件独立**；一旦两通道共享失效模式（同型相机、同一遮挡、同一位姿漂移），漏检数会被系统性低估、κ 被高估（乐观偏差）。所以迭代验证不是"多跑几次实验"，而是"构造一个与被验证系统失效模式**正交**的检验"；独立性缺失时，必须引入依赖敏感性下界或第三通道，并显式声明"未验证区域一律保守"。

关键反直觉点 4：anytime-valid 下界天然比固定样本下界保守，且随监控时间变长收紧得更慢；对罕见类别（轮椅、儿童、蹲姿）样本稀疏，κ̂⁻ 可能长期很低 → 活性坍缩。这是"验证的代价"，必须显式建模为**验证预算**与保守度之间的权衡。

**灵感 3（统一：主动验证 = active SLAM × 实验设计在线化）**
直觉：SLAM 的主动闭环（active loop closure）与迭代验证结合，就是**主动证书获取 (Active Certificate Acquisition, ACA)**：主动选择运动/视角/采样，以最大化安全关键区域证书不确定性的下降（位姿不确定 + κ̂⁻ 下界 + 覆盖）。这既是 active SLAM 的变体，也是"实验设计"的在线版：每一帧都在问"下一次观测放在哪里，能最快证伪/确认当前最危险的证书假设"。约束是不可为验证而冒险：只在安全可行动作集内选。

**三者如何统一**
统一为 **v21 之上的"框架一致 + 持续可证伪"层（Frame-Consistent, Falsifiable Certificate System, FC²）**：FTC 回答"这张证书属于哪个坐标系、现在还可信吗"；CPG-LCR 回答"闭环改坐标后哪些证书作废"；AVRM/CCRE/FLRI 回答"我们凭什么相信召回下界、以及被推翻后怎么办"；ACA 回答"下一步看哪里最能降低不确定性"。共享状态 ζ_fed/ζ_sem 扩展为 **ζ_fc = ζ_sem ∪ (G_t, {State_c}, κ̂⁻, L, B_val)**。统一准入门升级为 **HPC⋆ = HPC+ ∧ frame_ok ∧ validation_state=VALID**：几何 SAFE ∧ 规范允许 ∧ 负信息可靠 ∧ 框架一致 ∧ 验证存活，五者缺一即回退保守。核心安全铁律：**闭环修正与反例只能撤销自由空间赎回，绝不无膨胀地迁移旧结论**——故 `Exec_v22 ⊆ Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19 ⊆ Exec_v18` 由构造保持。

## 1. 研究问题（轮次升级版）

- **Q1（框架膨胀的可靠性）**：如何由位姿协方差 Σ_pose 与漂移模型导出 ε_frame(c,t)，使全局 CertBox 以 ≥1-δ 概率包含真实物体？位姿误差、定位误差、类先验收紧三者的置信预算如何分配（union bound 如何不浪费）？时间漂移上界在长任务中是否会主导膨胀、导致活性坍缩？

- **Q2（闭环一致性与失效单调性）**：闭环修正 δT 超过证书一致性裕度 m_c 时，如何只撤销自由空间赎回而不迁移旧结论？鲁棒后端（max-mixture / switchable constraints）如何拒绝"感知别名"造成的假闭环，同时不误拒真闭环？多机器人帧间相对位姿不确定下，障碍取并与投票保守去重如何双向保证单调？

- **Q3（anytime-valid 召回验证）**：如何构造对任意数据依赖停时有效的 κ̂⁻_t(α)？e-process 的 betting 策略如何选取以在"样本稀疏 + 长监控"下尽量紧？capture-recapture 在通道正相关时的乐观偏差如何用依赖敏感性下界或第三通道约束？未验证区域如何显式降级为保守？

- **Q4（反例追溯与主动验证）**：falsification event 如何沿证书依赖图追溯失效并保持审计链可回放？追溯失效与 v21 DCL 的义务/SafeStop 如何衔接而不造成连锁停机？主动证书获取如何在安全可行域内最大化"单位验证预算的不确定性下降"，且不因验证动作本身制造风险？

## 2. 设计原则（在 P34–P36 基础上新增 P37–P39）

**P37 框架相对律（Frame Relativity）**
所有几何证书必须在签发框架内定义，携带 `(frame_id, T, Σ_pose, t_issue, drift_bound)`；全局复用前按 `ε_frame = σ_radius(Σ_pose) + drift(t-t_issue) + drift_bound` 膨胀。闭环修正 `δT` 使 `m_c = ε_frame - ||δT|| < 0` 时，证书标记 STALE 并**撤销其自由空间赎回**，绝不无膨胀地迁移旧结论。框架失效（位姿不可信）⇒ 全域保守。

**P38 持续可证伪律（Continuous Falsifiability）**
每张 AbsCert 注册为一个可证伪假设；召回率下界由 **anytime-valid 置信序列**维护（任意停时有效，禁止 optional stopping）。falsification event 使该证书及其依赖证书失效，并更新 κ̂⁻。验证通道必须与被验证失效模式**正交**（独立模态/外部设施/人在环）；独立性不可保证时用依赖敏感性下界，且"未验证"一律保守。反例与失效只撤销赎回，安全继承不变。

**P39 主动验证律（Active Validation）**
运动/采样在满足安全约束的前提下，优先降低安全关键区域的证书不确定性（位姿 + 召回 + 覆盖）；验证动作本身必须落在安全可行域内，**不得为验证而冒险**。验证预算 B_val 有界，按"单位预算不确定性下降"排序分配。

## 3. 与基线的接口（如何退化）

- 位姿图失效/漂移超界 ⇒ 全局框架不可信 ⇒ 全域保守（比 v21 更保守），`Exec_v22 ⊆ Exec_v21`；
- 闭环大幅修正 ⇒ 相关证书 STALE、撤销赎回 ⇒ 收缩执行域（引理 164）；
- 帧感知去重不可用 ⇒ 退回 v21 NMS，但同时把帧不确定当作额外保守项 ⇒ 不产生假独立票；
- AVRM 失效（e-process 无法维护）⇒ 用最保守的先验下界 κ̂⁻ = κ_min ⇒ 比 v21 更保守；
- CCRE 无独立通道 ⇒ 不签发 AbsCert，声明 UNVALIDATED ⇒ 退化为 v21 的保守分支；
- FLRI 失效 ⇒ 任何 falsification 直接触发全域保守化 ⇒ 只收紧；
- ACA 失效 ⇒ 退回 v21 的被动证书获取 ⇒ 等价 v21；
- 全失效 ⇒ 完全回退 v21 ⇒ `Exec_v22 ⊆ Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19 ⊆ Exec_v18`（引理 169）。
- **安全继承**：FTC 只膨胀障碍/撤销赎回、CPG-LCR 只失效、AVRM 只可能下调 κ、FLRI 只失效、ACA 在安全约束内行动；任意失效都向更保守方向退化。

## 4. 预期贡献

1. **框架标签证书**：首次把位姿不确定性显式纳入感知/合规证书，给出"证书漂移"的形式化与膨胀界，使碰撞证书从"绝对几何安全"升级为"相对位姿安全"；
2. **闭环一致性重校**：给出闭环修正下证书失效与单调撤销的机制，证明"只撤销、不迁移"即可保持 `Exec_v22 ⊆ Exec_v21`；
3. **帧感知双向保守融合**：修正 v21 跨机器人 NMS 的帧对齐隐含假设，给出"障碍取并、投票保守去重"的双向单调规则；
4. **anytime-valid 召回验证**：用 e-process 置信序列替代静态 κ_c，给出任意停时有效的召回下界，封堵 E798 的 optional stopping 漏洞；
5. **捕获-再捕获召回估计**：在无全量真值时用双通道估计漏检数，并给出通道相关时的乐观偏差界与"独立性即验证有效性"的判据；
6. **反例账本与追溯失效**：把证书变成注册的可证伪假设，falsification 沿依赖图追溯失效、审计链可回放；
7. **主动证书获取 + HPC⋆ 统一准入**：把验证预算用于降低安全关键不确定性，`HPC⋆ = HPC+ ∧ frame_ok ∧ VALID` 闭环。

## 5. 本轮最大风险

**一句话**：验证只覆盖它看得见的世界，而最危险的失效恰好发生在它看不见的地方——若验证通道与被验证系统共享失效模式（同一检测器/同一传感器/同一位姿漂移），capture-recapture 会稳定地把"漏检"算成"没人"，anytime-valid 下界在"看似达标"中稳定地错，机器人将以"持续验证通过"的姿态撞上一个从未进入验证样本的人。
