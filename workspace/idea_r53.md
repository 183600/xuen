# 第 1 轮（灵感驱动研究循环第 1 轮；本轮灵感：技术路线图 × 场景驱动创新 × 视觉定位）· 从"安全证书架构"回到"评测协议对齐"：UniBot-V1 的胜负手在失败可检测性与场景格对齐，而非模型规模

> 承上：此前 52 轮把方案推到 v16「GroundEdge-GenSim」——适用域证书（TIX）、跨任务迁移证书（XFR）、组合代数（CRC）、仿真保真包络（SFE）、单向证伪（FDR）、真实锚点预算（RAB）、域漂移绊线（DST）、选择偏差校正（SBC）。这套东西本身是自洽的，但**它解决的不是 UniBot 这场比赛的瓶颈**。本轮的第一件事不是加一层，而是**修剪**：把 52 轮里最抽象、最不可证伪的部分降级为"评测协议自检工具箱"，把主线让位给三个能被排行榜证伪的命题。
>
> 修剪声明（写清楚，以免下轮又漂回去）：
> - **降级**（保留为工具，不作为主架构）：TIX / XFR / CRC / SFE / FDR / RAB / DST / SBC → 归并为"泛化证据分级 + 提交前自检"，只保留 fail-closed 与证据分级的工程纪律。
> - **删除**：与"多模型图钉 / 跨节点可信执行 / 分布式底座租约"有关的复杂度。官方规则明文规定**所有 32 个任务必须由同一模型完成、不得混用多模型**，因此 v15 的多模型安全论证在本赛事里几乎没有直接收益，只有"推理服务不崩"的最小价值。
> - **保留**：DDA 归因、证据分级、失败归因账本（作为实验纪律），以及"仿真只能否决不能批准"的思维（在我们自己的代理评测台上同样适用）。
> - **新主线**：把研究对象从"系统是否安全"换成"**在 320 次真机 episode 的有限统计预算下，如何最大化期望成功率**"。

## 0. 本轮的三条灵感各自指向什么

- **技术路线图**：不是画 PPT，而是回答一个残酷问题——**在有限时间/算力/真机额度下，先做哪一件事能把期望成功率抬上去最多**。因此本轮必须先算清"榜单的统计分辨率"和"每一分成功率值多少钱"。
- **场景驱动创新**：官方评测不是 32 个任务各测 10 次的随机抽样，而是**每个任务 10 次 = 5 类泛化 × 各 2 次**（位置 / 干扰物 / 桌面背景 / 未见物品 / 人为干扰）。这是一个**被写进规则的 160 格场景矩阵**（32×5）。凡是能对齐这 160 格分布的训练/增强，收益是结构性的；凡是只在"标准布置"上刷分的，收益会被泛化格吃掉。场景驱动不是口号，是**训练分布与评测分布的同构化**。
- **视觉定位**：榜首不到 30%，意味着七成失败。而官方 rubric 把"抓住 X"和"把 X 插入/挂到 Y"分成 2–3 个带权重的子目标（最后一步常占 40 分）。失败最可能的形态不是"不会做"，而是**"不知道该对哪一个/哪一个位置做"**（尤其在未见物品、移动、被人拿走之后）。视觉定位不是感知子模块，而是**可被验证、可被重估、可以驱动重试的状态变量**。

## 2. 从事实到策略：六条推论

**推论 1（统计分辨率）：榜首之间的差距在噪声内。**
一次完整提交 = 32 任务 × 10 次 = **320 个二值 episode**。总分均值粒度 = 0.1/32 = **0.3125 分**；在 p≈0.30 处 SE = √(0.3·0.7/320) ≈ **2.56 分**，95% CI 半宽 ≈ **5.0 分**。占位榜单里第 1 名 29.7 与第 2 名 28.5 相差 1.2 分（≈3.8 个 episode）≈ **0.47σ**。结论：**"再挤 1–2 分"没有意义；能被验证的目标是"结构性的 +5 分以上"**。路线图必须以"能否带来 ≥5 分"为门禁，而不是以"某个模块涨了 0.4 分"为门禁。

**推论 2（步骤分不是独立杠杆）。**
占位榜单里步骤分/成功率之比在模型级 1.305–1.371、任务级 1.339–1.345，256 个 (模型,任务) 对几乎同一常数；且 2 步任务与 3 步任务的比值没有结构差异。这与"步骤分是独立的偏 credit"的解释不符，更像统一缩放。叠加 F3 的排序规则（成功率优先、步骤分仅在并列时决胜）→ **步骤分只当作诊断量（失败卡在哪个子目标），不当作优化目标**。

**推论 3（真正的杠杆是"乘法结构"，不是"加法改进"）。**
rubric 天然把每个任务切成 2–3 个串行子目标。若各子目标条件成功率 p 独立，整题成功率 ≈ p^k。占位榜单 p≈0.30 ⇒ 若 k=3 则 p≈0.669。**只要能检测"这一步没成"并就地重试一次**，单步有效成功率升到 p(2−p)，整体从 p³ 升到 [p(2−p)]³：p=0.669 时 **0.30 → 0.70**；即便检测召回 0.8、恢复成功率 0.6（有效 p*=0.669+0.331×0.48=0.828），整体仍有 **0.30 → 0.57**。
这是本轮最重要的判断：**在 p≈0.67 的区间，"失败可检测性 + 子目标级恢复"的期望增益远大于"更强的策略头"**（后者要把 p 从 0.669 提到 0.75 才能拿到 +8 分，而前者是一阶结构改动）。也解释了为什么占位榜单里同一模型在不同任务上会出现 9% 与 40% 的巨大落差——串行子目标里任何一环崩掉，整题就归零。

**推论 4（评测协议本身是一张可利用的网格）。**
F2 + F6 把评测定义成 32×5 的**场景格**。这意味着：(a) 训练增强可以精确对着格做，而不是"泛化地"做；(b) 每个格都能构造**可证伪的内部指标**；(c) 未见物品格（2/10 次）与人为干扰格（2/10 次）合计 **40% 的运行天然处在训练分布之外**——这两格必须专门设计，不能指望"大模型自然泛化"。人为干扰的具体形态（F6：中途拿走、拔起、挪底座）是**可枚举、可合成**的。

**推论 5（视觉定位要做成"可验证状态"，不是"更好的特征"）。**
评测接口**不给深度**，但给两路头部相机；数据集标明它们是**已校正双目**（F11）。因此可以在参赛端自算视差 → 米制深度 → 基座系 3D 目标点（配合 F13 的腰部角解析补偿）。这让"把插头插进第 1 个插孔""挂到标记位"这类**毫米级末步**拥有可监督、可验证的 3D 目标，而不是让 VLA 在像素空间里猜。同时，视觉定位输出必须带**置信度与一致性判据**（目标是否还在原位/是否被人移动/是否已被抓住），否则它没法驱动重试（推论 3 需要检测器）。

**推ion 6（接口工程不是小事，但也不是研究贡献）。**
F8/F10：N 端口并发、状态隔离、延迟与抖动被记录并可能影响"可信度"。这是**门槛型工程**：做不好直接判死刑，做得好不加分。因此路线图里它必须被安排在早期（否则后面所有实验都在不稳定地基上跑），但**不占用研究叙事**。

## 3. 三条灵感如何合成一条主线

主线假设（**H53**）：
> **在 UniBot-V1 上，最大期望增益来自"把不可见的失败变成可见、可判定、可重试的子目标状态"，并用 160 格场景矩阵同构化训练分布；模型规模、架构（VLA vs World Model）是次要变量。**

H53 的三个可操作支柱：
1. **看得见**（视觉定位立体化 + 置信度）：把"目标是谁/在哪/是否还在"变成显式变量；
2. **断得掉**（rubric 子目标栈 + 失败检测）：把"做没做成"变成显式判定；
3. **接得上**（子目标级恢复 + 场景格课程）：把"没做成之后怎么办"变成可训练的策略。

三者构成闭环：**定位 → 执行 → 判定 → 恢复/重规划**，与推论 3 的乘法增益严格对应。技术路线图只是把这个闭环按"每步能带来多少期望分"排序。

## 4. 自我批判：本轮可能错在哪（写下来逼自己下轮检验）

- **批判 A：H53 假设 rubric 子目标可在线判定。** 官方并未公布"步骤分"的可观测判据（我们只能看到 rubric 文本）。如果"抓住插排"与"抓住插头"在评测端是人工/VLM 判定且带延迟，选手端的自建判据只是代理，会出现"自认为失败→重试→其实已得分"的浪费，或"自认为成功→不重试→其实没得分"的损失。**必须先在单任务通道（不计分）上做判据一致性标定**。
- **批判 B：恢复在人为干扰格常常不可恢复。** F6 的"中途把锁拿走"本质上无法在原计划内完成；这类 episode 的上限就是失败，除非允许"改为报告/替代目标"（而 rubric 只认原目标）。因此恢复增益在 5 类格中**高度不均**，不能按平均估。
- **批判 C：占位榜单不可作为事实。** F14 已说明榜单 JSON 是占位随机数据；因此"榜首 <30%""模型间任务强弱不相关（pairwise Spearman ρ≈0.10）""每任务最优 oracle 33.96 vs 最佳单模型 29.7"这些数字**只能当作结构假设**，必须在真实榜单或我们自己的真机批次上复核。本轮所有以这些数字为前提的收益估计都标注为"待验证"。
- **批判 D：单模型规则会否否掉"专家路由"。** F4 禁止"混用多个模型"。共享主干 + 簇级 LoRA 的条件化推理是否被认定为"一个模型"存在解释风险。保守起见，本轮把它排为 P3 可选项，且优先级低于前三个支柱。

## 5. 本轮最小可证伪实验（下一轮就有结论）

- **E151 判据一致性**：在 6 个任务 × 10 次上，同时记录"自建子目标判定"与官方返回的步骤分/成功结果，估计一致率与误判代价。若一致率 <80%，H53 的"检测"支柱失效，必须先修判据。
- **E152 恢复增益上界**：离线用数据集构造"人为制造失败状态"的恢复片段，测 p* = p(2−p) 的经验值；再在真机单任务通道上做 3 组对照（无恢复 / 检测+重试 / 检测+重试+换手）。
- **E153 格间落差**：用 160 格代理评测台测出 5 类泛化各自的成功率差；若某格差 >15 分，说明该格是独立课题（对应"未见物品"与"人为干扰"两格）。
- **E154 立体定位精度**：在数据集上验证视差→基座系 3D 的重投影误差（目标像素→反投影→与 gripper 事件时刻的 EE 位姿比对），目标 <2cm。

## 6. 本轮结论（先给结论，再给证据）

如果上述四条实验按预期成立，那么**最值得押注的创新点**是：

> **"子目标级失败检测与恢复"（IP-110 RSC），配套"立体度量视觉定位"（IP-109 SMG）作为检测器的观测来源、"演示反推伪标签"（IP-111 DPG）作为零标注训练来源、"160 格场景格课程"（IP-107 SGC）作为泛化增益来源。**

因为在 320 episode 的统计预算下，"能看出失败并重试"是唯一一个能在**不增加模型规模**的前提下、同时抬升**期望成功率**与**步骤分**的结构性改动；其余选项（更大的 VLA、World Model、更多合成数据）都只是把 p 从 0.669 往上挪 0.03–0.08 的加法改进，而当前榜单分辨率（0.31 分/episode、SE≈2.6 分）根本分辨不出来。

**下一轮计划**：用本轮确立的事实与 E151–E154 的设计，去抓取并核验（a）官方"步骤分"定义的更多细节（登录后文档 / 单任务通道返回体）、（b）真实榜单上线后的第一批真实数据、（c）32 个任务在 5 类格上的官方具体设定表（飞书 wiki 电子表格需 JS 渲染，需换手段抓取），并据此修剪 SGC/路由/延迟工程三条支线的优先级。
