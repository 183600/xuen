# 第 4 轮（灵感驱动研究循环·本轮灵感：「语音合成」×「模型预测控制」）

> **基线**：第 3 轮产出 MetricVoiceGauge-NCD-HUTDH-v21+IP-425–430（SDC/CAC/DCL/GIC/HPC+/CFC+；其上承 v20 的 PCA/CTS/CFC/HPC/CFCtrl 与 v19/v17 证书体系）。
> 本轮纪律：**承诺必须可递归续期、必须说得清楚、必须做得到；说不出口或做不到的承诺不是承诺，只是噪声**。不推倒 v21：SDC/CAC/DCL/GIC/HPC+/CFC+ 全部保留。本轮只做一件事：**在 v21 的语义-规范层之上加一层"承诺-时序"层（Commitment-Temporal Layer, CTL），把"此刻安全"升级为"可持续安全 + 可沟通承诺"，并顺手封堵 v21 之外的新风险——承诺悬崖与施行式语音**。

## 0. 直觉与动机

**灵感 1（语音合成 → 证书的下行外化：说出口的话是承诺，不是通知）**
直觉：v21 已经能证明"我会让行""我将从左侧通过"，但这些证明只活在证书里，人听不见。语音合成（TTS）补上的正是这条缺失的**下行通道**：把证书外化为一句有时长、有韵律、可懂的话。关键反直觉点有三层。第一，**TTS 不是装饰，而是承诺的物理载体**：话语的声学时长是控制约束——话没说完，承诺点不能到；话语的语义必须由证书**确定性编译**，不能自由生成，否则会"幻觉承诺"（说了证书没证明的事）。第二，**韵律是紧迫度的编码**：语速、音高、重音、停顿对应 TTC 与让行方向，使"还有 1.2 秒"这件事本身可被人感知。第三，**可懂度是可标定的**：在给定噪声下，"人正确识别承诺模式"的概率可以像检测召回率一样被下界约束；噪声过大时，正确动作是换通道（视觉/灯光）或减速，而不是把同一句话喊得更大声。

严谨定义：给定证书 `c_t` 与 RFC 计划族 `Π_t`，编译器 `Compile: (c_t, Π_t) → u_t = (txt, prosody, dur, chan)`，其中 `txt` 来自有限模板文法 `G`（而非自由文本），满足 `sem(txt) = mode(Π_t)`、`dur(u_t) ≤ TTC_commit - τ_human`、`I(u_t, noise) ≥ 1-β`。若不存在满足预算的 `u_t ∈ G`，则收缩计划（减速/等待）或 SafeStop——**绝不用更长的句子去追赶更短的时间窗**。

**灵感 2（模型预测控制 → 从快照安全到可递归续期的安全）**
直觉：v21 的 HPC+ 是一个**快照准入**：此刻几何 SAFE、规范允许、负信息可靠。但"现在安全"不等于"下一步还有安全解"——机器人可能被行人逼进一个此刻合规、下一步必然违规的死角。这正是 MPC 的用武之地：**递归可行性（recursive feasibility）+ 终端不变集（terminal invariant set）** 给出"可持续安全"——每一步都存在一条 H 步可行轨迹，且终点落在"能安全停住"的终端集。关键反直觉点：**一个"现在有效但通向死胡同"的证书不是安全证书**；安全必须是可递归续期的。再叠加 tube MPC 的不确定性管，把 v21 的 CertBox 定位误差、覆盖不确定性、意图不确定性，以及本轮新增的**语音诱发扰动**（人听到喊话后可能惊扰、后退、抢行）统一进约束收紧。

严谨定义：`RFC_t = ∃π_{0:H} [∀k<H: x_k ∈ X_k^cert ∧ u_k ∈ U ∧ x_{k+1}=f(x_k,u_k); x_H ∈ X_term ⊆ X_stop]`，其中 `X_k^cert` 由 v21 证书膨胀得到，`X_stop` 是可安全停住集；鲁棒管 `S_{k+1}=A S_k ⊕ W_k`，约束收紧为 `z_k ∈ X_k^cert ⊖ S_k`。递归可行性由终端不变集归纳保持；若 `X_stop` 不可达或约束收紧后可行域为空，立即 SafeStop，而不是"再试一步"。

**三者如何统一：承诺 = 时序化的证书外化**
v21 的证书回答"此刻能不能动"，v22 的 CTL 回答"这个承诺能不能被递归续期、能不能在人听懂之前说清楚、说了之后能不能做到"。统一为 **v21 语义-规范层之上的承诺-时序层**：RFC 回答"承诺是否可持续"，RTC 回答"在不确定性下是否仍然可持续"，PTCS 回答"如何把承诺在时间预算内说清楚"，SDCM/CNP 回答"说了之后是否做到、做不到了如何撤回"。共享状态扩展为 `ζ_com = ζ_sem ∪ (H_t, X_term, U_t, u_t, commit_state, sdcc)`。统一准入门：**HPC++ = (HPC+, RFC, SDCC)**——几何/规范/负信息（HPC+）∧ 时序可续期（RFC）∧ 说做一致（SDCC）才进入执行。安全继承的关键：RFC 只过滤计划、RTC 只收紧约束、PTCS/SDCM 只加时间与语义约束、CNP 只允许向更保守撤回，语音输出本身**不改变几何可执行集**，故 `Exec_v22 ⊆ Exec_v21`。

## 1. 研究问题（轮次升级版）

- **Q1（递归可行性与证书悬崖）**：在人以有界速度移动、遮挡与覆盖图时变的情形下，如何定义终端不变集 `X_term` 与可安全停住集 `X_stop`，使 RFC 的归纳保持成立？"约束收紧速度快于管吸收速度"的临界条件是什么？如何提前 ≥τ_warn 检测"证书悬崖"（当前可行但 H 步后必然不可行）？

- **Q2（鲁棒管与语音诱发扰动）**：如何把 CertBox 定位误差、覆盖不确定性、意图不确定性与**语音惊扰反应**统一为扰动集 `W_k`？`W_ann` 如何标定（人群、年龄、文化、噪声）？tube 收紧后可行域缩小的活性代价如何与 v21 AbsCert 的"有偿赎回"叠加而不互相抵消？

- **Q3（承诺的编译与可懂度）**：如何从证书确定性编译出有限模板话语，使语义与计划族严格一致、时长满足 `dur + τ_human ≤ TTC_commit`？噪声/多语言/听障下的可懂度下界如何标定与在线监控？韵律参数（语速/音高/重音）如何映射到紧迫度与方向而不引发惊扰？

- **Q4（说做一致与撤回语义）**：如何定义承诺计划族 `Π_ann` 的容差，使执行偏差可检测又不过度约束？重宣布、撤回、SafeStop 的时序与滞回如何设计，避免"狼来了"式信任崩塌？"静默 ≠ 同意"如何在协议层强制？

- **Q5（实时与共享预算）**：RFC + tube + 语音编译如何在 10Hz 证书更新、50Hz 控制路径下共享 12ms 预算？显式/热启动 MPC 的网格命中率与回退策略如何保证不超时？语音合成延迟与抖动如何与 v17 APS 新鲜度阶梯对齐？

## 2. 设计原则（在 P34–P36 基础上新增 P37–P40）

**P37 承诺即约束律（Commitment-as-Constraint）**
任何说出口的承诺必须是某个 RFC 认证计划的**确定性投影**：`u_t = Compile(c_t, Π_t)`，`sem(u_t) = mode(Π_t)`，且 `Π_exec ⊆ Π_ann`。话语时长是硬约束：`dur(u_t) + τ_human ≤ TTC_commit`。不得用自由生成文本承诺证书未证明的模式；不得用更长话语追赶更短时间窗。语音输出不扩大几何可执行集。

**P38 递归可行律（Recursive Feasibility）**
准入要求存在 H 步可行计划且终端集 `X_term ⊆ X_stop` 正不变；每一步的移位计划必须仍在鲁棒管内。递归可行性丧失时：若早于 `τ_retract`，允许向更保守计划撤回并重宣布；若晚于 `τ_retract`，只允许 SafeStop。**安全是可续期的，不是一次性的。**

**P39 说做一致律（Say-Do Consistency）**
执行轨迹必须始终落在承诺计划族 `Π_ann` 的容差内；任何超出容差的模式变化必须在 `τ_retract` 前触发重宣布/撤回，禁止静默切换。人的确认（ack）只是**可选证据**，可提高效率，绝不作为几何安全的前置条件——**静默 ≠ 同意**。

**P40 时间预算律（Temporal Budget）**
语音编译、协商、RFC 求解共享硬时间预算；控制路径只做 O(1) 的"当前承诺模式 + 撤回标志"查询，绝不同步等待 TTS 或 QP。预算不足时按"缩短话语 → 减速/等待 → SafeStop"的顺序降级，绝不压缩 `τ_human`。

## 3. 与基线的接口（如何退化）

- RFC 失效（求解超时/不可行）⇒ 回退 v21 快照准入，并强制低速 + 预置制动；若连 `X_stop` 可达性都不能证明 ⇒ SafeStop；
- RTC 失效 ⇒ 用最坏情形膨胀（更保守），等价于缩小 `X_k^cert`；
- PTCS 失效（TTS/通道故障）⇒ 无语音承诺，退回 v21 纯几何/规范准入，但强制静态人距限速（人不知道意图）；
- SDCM 失效 ⇒ 冻结模式，只执行已承诺计划的最保守前缀；无法确认前缀安全 ⇒ SafeStop；
- CNP 失效 ⇒ 只执行最短承诺（停车/让行），不发起新承诺；
- EC-MPC 超时 ⇒ SafeStop；
- 全失效 ⇒ 完全回退 v21 ⇒ `Exec_v22 ⊆ Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19 ⊆ Exec_v18`。
- **安全继承**：RFC 只做计划集过滤（存在性 + 终端集），RTC 只收紧约束，PTCS/SDCM 只增加时长/可懂度/一致性义务，CNP 只允许向更保守撤回；语音是"说"，不是"动"，不改变几何可执行集。任意失效都向更保守方向退化。

## 4. 预期贡献

1. **递归可行证书（RFC）**：首次把 v21 的快照准入升级为可递归续期的时序安全，给出终端不变集 + 可安全停住集的双重条件，封堵"证书悬崖"；
2. **鲁棒管 + 施行式扰动**：把检测/覆盖/意图/语音惊扰统一进 tube MPC 的约束收紧，给出包含率与活性代价的显式权衡；
3. **证书到语音的确定性编译**：承诺即约束，有限模板文法 + 时长预算 + 可懂度下界，杜绝 TTS 幻觉承诺，把"说清楚"变成可审计证书；
4. **说做一致与撤回协议**：给出承诺计划族容差、重宣布/撤回/SafeStop 的时序语义与"静默≠同意"的强制条款，避免信任崩塌；
5. **实时可行性**：显式证书 MPC + 预合成模板 + 10Hz/50Hz 分层，保住 12ms 控制预算；
6. **HPC++ 五证一体**：HPC+ ∪ RFC ∪ SDCC 统一准入门，`Exec_v22 ⊆ Exec_v21 ⊆ ...` 闭环。

## 5. 本轮最大风险

**一句话**：本方案把"说出口"当作可审计的承诺，但承诺是**施行式（performative）**的——语音本身会改变人的行为（惊扰、后退、抢行、误解），而 RFC 的鲁棒管只界定了几何与标定扰动，界定不了语义反应；于是机器人可能"递归可行地"撞上一个因它自己喊话而走进路径的人——**"合规的自我实现事故"**。
