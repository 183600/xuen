## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（多视角视觉 → 我们一直只用三只眼，而第四只眼恰好是唯一的「接触传感器」）**

直觉：机器人有头部双目 + 两个腕部相机，但官方基线训练只喂 `head_stereo_left` + 两腕（F22）——右目被丢掉了。多视角不是「多几帧」，而是三件别的东西：(a) **度量几何**——头部双目已做极线校正，视差直接给米制深度，能三角化目标与夹爪的 3D 点（F23）；(b) **遮挡冗余**——腕部被手挡住时头部还在看，头部被手臂挡住时腕部还在看；(c) **跨视角不一致 = 物理事件**——没有力/触觉通道（F20），但接触会破坏「同一刚体在两视角下应一致」的假设，于是**两目之间的重投影/光度残差就是一台免费的、物理上可解释的接触/滑移传感器**。核心反直觉点：**我们缺的不是更强的视觉 backbone，而是把已经被采集、被标定、却在训练里被丢弃的第二目用起来，并把「两目不一致」当成一种传感信号。**

严谨定义：设视角集合 `V={L,R,wL,wR}`，相机投影 `π_i(X)=K_i[R_i|t_i]X`。头部双目经极线校正后，视差 `d(u,v)` 与深度满足 `Z=f_x b/d`（`b` 为基线）。三角化得到目标/夹爪关键点 `X_t∈R^3`。定义跨视角一致性残差
`ρ_t = median_{p∈Ω_t} |I_L(p) − I_R(p − d(p))|`，`Ω_t` 为目标∪夹爪掩码；定义**接触代理** `c_t=1[ρ_t 超基线且持续 k 帧]`，**滑移代理** `s_t=1[夹爪闭合 ∧ ||X_t^obj − X_t^gripper|| 的变化率 > τ_s]`。定义**第四只眼缺口** `Δ_4 = V(4 views) − V(3 views)`，以及**有效视角覆盖** `κ_t = 跨视角可见目标像素/目标总像素`。训练目标可写为
`L = L_action + λ_1 L_depth + λ_2 L_crossview + λ_3 L_contact`；
其中 `L_depth/L_crossview` 可用几何自监督（无需人工深度标签），`L_contact` 用 `c_t/s_t` 作弱标签。

**灵感 2（单模型多任务 → 单模型不等于单条稠密通路，接口真正锁死的是「一个类、一个控制空间、一个 chunk 长度」）**

直觉：32 个任务、平均分被最弱任务支配（P1），而赛制要求一个 policy 类同时服务全部任务（F21）。大多数队伍会走两个极端：训一个巨大稠密模型，让弱任务被强任务淹没；或训 32 个模型，违反单模型约束。正确的框架是**共享容量 + 任务条件稀疏计算**：一个检查点里放共享主干、任务族专家（LoRA）与一个路由器；指令已经标识任务（F20），路由几乎不需要猜，真正难的是**任务间干扰**与**最弱任务**。更关键的接口事实是：`control_space` 只能全局二选一、`action_chunk_size` 全局固定（F21）——所以「统一」必须发生在动作表征层（选 `ee`，F26），而「自适应 chunk」不能在返回长度上做，只能在固定 chunk 的边界上做决策。核心反直觉点：**在固定参数预算下，最优的「单模型」未必是一条稠密通路；一个检查点 + 任务条件稀疏专家可以更强，只要路由器与主干联合训练、且能蒸馏回稠密模型。**

严谨定义：一个检查点 `Θ` 含共享主干 `f_θ`、专家库 `{g_e}`、路由器 `q(e|z_t)`，`z_t=[指令嵌入, 首帧场景 token]`。策略
`π(a|x,t)=Σ_e q(e|z_t) g_e(f_θ(x))`，
约束为：`Θ` 只有一份、一个 `control_space`、一个 `T_a`。定义**任务干扰矩阵** `M_{tt'}=cos(∇_θ L_t, ∇_θ L_{t'})`（在共享参数子集/动作专家上估），任务族划分 `P` 使跨族负干扰 `Σ_{t,t'∈不同族} max(0,−M_{tt'})` 最小。定义**容量分配** `r_t`（LoRA rank/epochs）在预算 `Σ_t r_t ≤ R` 下最大化最弱任务收益。定义**分数感知目标** `J_λ=(1−λ)·mean_t S_t + λ·CVaR_α(S)`（或 `max_t S_t`），其中 `S_t` 为任务 `t` 的成功率+步骤分估计；聚合权重未知时用 minimax 而非赌一个权重。

**两者统一**：多视角给出一个**共享的米制 3D 表征**，它让 32 个任务不必各自学一套视觉特征，从源头降低任务干扰；单模型多任务则需要**条件动作容量**来隔离仍然冲突的技能。合起来是本轮主命题：**共享几何表征，条件动作容量**——上一轮的数据引擎是燃料，本轮补的是「感知前端」与「容量后端」。三句话：多视角回答「在哪里、碰没碰到」，单模型多任务回答「谁来做、给多少容量」，数据引擎回答「拿什么教」。

## 2. 对第 2 轮痛点的增量修订

- **P1（弱任务支配平均）升级为 P1''（任务干扰 × 容量错配 × 采样偏差）**：不仅数据权重，参数容量与损失归一化也会让弱任务吃亏；长任务按帧采样会被系统性过权（F27）。
- **P2（泛化缺口）补几何维度**：位置/未见物品轴的误差有一部分来自单目尺度歧义与遮挡；多视角可把「猜深度」变成「算深度」。
- **P4（无触觉）补第一条物理路径**：跨视角一致性是无需额外硬件的接触/滑移代理，但它不是力传感器，不能测力的大小与方向。
- **P5（时间压力）补接口硬约束**：自适应 chunk 不能在返回长度上实现（F21），只能在固定 chunk 边界重规划；接触任务的反应延迟下界 = `T_a/15Hz`。
- **P6（部署）补多视角与路由开销**：四路编码 + 立体匹配 + 路由器会吃延迟；必须用「三路 VLM + 双目几何 sidecar」而不是四路全进大模型。
- **P8（示教质量）补任务不均衡**：episode 数近均匀但帧数差 2.7×（F27），质量加权要与长度归一化一起做。
- **新增 P9（第四只眼缺口 / 标定漂移）**：训练三路、评测四路是协变量偏移；更麻烦的是 `camera_params` 随场次变化（F24），不能假设一套标定走天下。
- **新增 P10（路由塌缩 / 单模型边界）**：任务条件专家可能塌缩成少数专家；类内几何 sidecar/检索库是否算「单模型」仍需书面确认（承接 PR2）。

## 3. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

- **Q9（多视角几何的可迁移性）**：数据集标定（F23/F24）能在多大程度上迁移到评测相机？第四只眼对 3D 关键点/深度/抓取点的增益在哪些任务、哪种遮挡条件下为正？标定不确定时，如何优雅退化为尺度无关的跨视角一致性？
- **Q10（接触代理的可辨识性）**：跨视角残差能否把「接触/滑移」与「光照/高光/遮挡边界」分开？在无人工力标签下，用夹爪闭合+物体运动构造的弱标签能训练出多高 precision/recall 的接触检测器？误报触发恢复的代价如何门控？
- **Q11（条件容量的净收益）**：在「一个检查点、一个 control_space、固定 chunk」的硬约束下，任务族 LoRA 路由 + 最弱任务目标能否同时抬高 32 任务平均分与最弱任务分？容量/延迟前沿在哪里？稠密蒸馏回退会损失多少？

## 4. 设计原则（新增 PR6–PR8，其余保留）

- **PR6 共享表征优先律**：优先做能改善所有任务共享表征的改动（多视角 3D、标定、视角增广），再做任务特化；共享表征越好，单模型多任务的干扰越小。
- **PR7 单检查点条件容量律**：任何条件计算必须在一个检查点内、且必须有稠密蒸馏回退；不允许部署 32 份权重；路由器必须与主干联合训练并做负载均衡。
- **PR8 先用几何、再加学习**：能用已标定的双目/运动学算出来的量（深度、关键点、接触残差），不要用新网络去猜；几何是免费监督，也是可解释的安全边界。
- PR1–PR5 保留（第 1/2 轮 §4）。

## 6. 本轮最大风险

**一句话**：I10 的米制几何依赖「数据集标定能迁移到评测相机」而 F24 已证明标定随场次变化、I11 的条件容量又依赖「类内多专家仍被判定为单模型」——这两条只要有一条不成立，第四只眼与任务路由就会同时退化为昂贵的装饰，甚至因误接触触发和路由塌缩拉低原本稳的任务。

## 7. 下轮迭代计划（深化与修剪，不推倒）

- **深化**：I10（标定置信阶梯：尺度无关一致性 → 相对深度 → 标定/自标定米制 3D；在 3 个接触任务上标接触/滑移 precision-recall）；I11（32×32 干扰矩阵的最小代理 + 任务族划分 + top-1 LoRA 路由原型）；I12（离线任务分数矩阵 + DRO 权重更新）。
- **修剪**：I4 从「自适应 chunk」降级为「固定 chunk + 边界重规划」，若 L0 显示接触任务反应延迟不可接受则进一步降为只做安全保持；I7 继续待裁。
- **待核实**：评测相机是否与任一训练场次同标定（F24）、N 值、步骤分精确公式、官方对「类内多专家/检索库/几何 sidecar」的单模型边界书面口径、四路观测在评测端是否始终同步。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I1 v3 考纲校准五轴增广引擎 ★★★★★
- **动机**：计分 32 任务在 5 轴泛化条件下评测（P2/F2）；第 2 轮「位置重拼接」有物理不可行动作风险；本轮补视角/遮挡压力。
- **本轮深化（多视角）**：①**视角增广**：训练时随机 dropout 一路腕部/头部视角、左右目交换、合成遮挡边界，让策略不依赖固定四路输入；②**立体 3D 位置扰动**：用头部双目把目标抬到 3D，平移后重投影到所有视角，替代 2D inpainting 的「贴纸感」与物理不可行；③考纲卡新增「视角/遮挡」条件（若官方计分轴含此项，待核实）。
- **与现有方案差异**：2D 增广只改像素不改几何；本点用已标定双目做几何一致的 3D 增广，并与 I10 共用标定置信阶梯。
- **技术可行性**：高。标定可用时走 3D；标定不确定时自动退回 2D/平移不变增广。
- **所需资源**：1×24GB GPU；分割 + 重投影数据管线 2 人周。

### 1.1 标定置信阶梯 + 跨视角接触代理（I10）

```python
# 头部双目已 rectified；b 为基线，fx 来自标定库/自标定；SGBM 为确定性经典算法
def stereo_depth(left, right, calib, conf):
    disp = sgbm(left, right)                      # 240x320 输入，GPU/CPU 均可
    if conf == "L0_scale_free":
        return normalize(disp)                    # 尺度无关：只用于相对比较
    if conf == "L1_relative":
        return calib.fx * calib.b / (disp + 1e-6) # 相对深度，不保证米制
    return calib.fx * calib.b / (disp + 1e-6)     # L2/L3：米制

def contact_slip_proxy(left, right, calib, conf, gripper_closed, prev_obj_xyz):
    disp = sgbm(left, right)
    Z    = stereo_depth(left, right, calib, conf)
    obj  = open_vocab_segment(left, instruction)  # SAM/检测，目标掩码
    xyz  = triangulate(obj.mask, disp, calib)     # 3D 质心/关键点
    rho  = photometric_residual(left, right, disp, mask=obj.mask | gripper_mask(left))
    contact = rho > tau_rho                       # 跨视角不一致 = 接触候选
    slip    = gripper_closed and norm(xyz - prev_obj_xyz) > tau_s
    return contact, slip, xyz, rho

# 标定库选择：用已知 EE pose + 夹爪投影重投影误差选场次标定
def select_calibration(calib_bank, head_left, ee_pose):
    return min(calib_bank, key=lambda c: gripper_reproj_error(c, head_left, ee_pose))
```

### 1.2 干扰矩阵 + 单检查点任务族 LoRA 路由（I11）

```python
def interference_matrix(tasks, model, probe_batches, params):
    G = {}
    for t in tasks:
        g_t = grad(loss(model, probe_batches[t]), params)   # 只取动作专家/共享子集
        for u in tasks:
            g_u = grad(loss(model, probe_batches[u]), params)
            G[(t, u)] = cosine(g_t, g_u)
    return G                                                   # 32x32，离线 L0

def partition_families(G, twin_prior, n_families=5):
    # 先验：孪生表；修正：最小化跨族负干扰 Σ max(0, -G)
    return cluster(G, prior=twin_prior, k=n_families)

class SingleCheckpointMoL:                  # 一个 checkpoint，不是 32 份权重
    def __init__(self, trunk, experts, router, families):
        self.trunk, self.experts, self.router = trunk, experts, router
        self.task_to_family = families
    def get_action(self, obs):
        z   = encode_task(obs["observation.language"], first_frame(obs))
        fam = self.router.top1(z)           # top-1，避免抖动与延迟
        return self.experts[fam](self.trunk(obs))

def train_step(obs, action, task):
    fam  = policy.task_to_family[task]
    loss = policy.experts[fam].loss(policy.trunk(obs), action)
    loss += lambda_bal * load_balance(policy.router, batch_tasks)
    loss += lambda_ent * entropy(policy.router)
    return loss
```

## 2. 实验设计（分级消融协议 v3）

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0 | I10 标定迁移/第四只眼/接触代理；I11 干扰矩阵/路由 vs 稠密；I12 DRO vs 均匀；I1 视角 dropout；I4 T_a 回放 | 离线（免费） | I10：标定误差 < 阈值且接触 PR 达标；I11：最弱任务 Δ>0 且平均不退；I12：CVaR 提升 |
| L1 | 2^(k-p)：多视角开关 × 路由开关 × DRO 开关 × 视角 dropout 剂量；I4 T_a∈{4,8,16} | 离线 + 少量真机 | 主效应显著 ≤3 组合进 L2 |
| L2 | top 组合真机确认：≥2 任务 × 各 2 次；优先最弱 3 任务与 3 个接触任务 | 单任务通道 | 真机增益 ≥ 离线预测 50%；无动作健康度回归 |
| 门禁 | PR4：run_client 全流程 + p99 + 动作健康度 | 本地 stub | 0 拒绝动作、p99 < 40ms |

**首批 L2 排队**：①I11 路由基线（32 任务诊断矩阵）→ ②I10 标定迁移 + 接触代理 → ③I12 最弱任务 DRO → ④I4 固定 T_a 确认 → ⑤I9 未见轴抽测。

## 6. 本轮最值得押注（一句话）

## 7. 本轮最大风险（一句话）
