# 第 4 轮 · ECHO-LOOP：多视角回声、关节回声、原型回声

> 检索/复核日期：**2026-10-29（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。状态文件上一轮是第 12 轮 CHUNK-SERVO；本轮是本会话灵感循环第 4 轮，研究线顺延为第 13 轮。三个灵感词是「多视角视觉」「关节驱动」「快速原型」。本轮不推倒 FACT-VLA、GEO-RESIDUAL、CHUNK-SERVO，而是把 CHUNK-SERVO 的「单路视觉 + EE 伺服」升级成「多视角决策 + 关节空间执行 + 原型检索」，并把上一轮的两个事实错误当场修掉。

## 0. 先给结论：缺的不是第四个模型，是三种「回声」

我先把三个词各做一次最诱人的联想，再看它们在 UniBot 里会不会变成陷阱：

| 灵感词 | 最诱人的做法 | 为什么在 UniBot 里危险 | 本轮采用的合规版本 |
|---|---|---|---|
| **多视角视觉** | 再训一个多视角 3D 大模型，或在线跑 3DGS/NeRF | 单模型规则；6B 已经很大；每端口多一份 GPU；远程 RTT 不允许 | **MV-ROUTE**：同一 checkpoint，按阶段路由 4 路相机；训练时做视角 dropout；推理时用 2 个视角子集的动作一致性做不确定性门控 |
| **关节驱动** | 直接训一个关节空间 VLA，替代官方 WLA | 官方 WLA 是 EE 动作头；从零训关节 VLA 成本高；跨任务泛化未必更好 | **JOINT-ECHO**：保留 WLA 的 EE 意图，用解析 IK + 关节空间轨迹执行；用「指令关节 − 实测关节」的跟踪误差做无传感器接触/人为干扰回声 |
| **快速原型** | 给每个任务快速搭一个专用策略/夹具 | 规则禁止逐任务多模型；改硬件不现实；32 个任务会拖垮工程 | **PROTO-GRAPH + PROTO-48**：从 33k 成功演示里建运动基元图；新任务只加任务卡和演示索引，不重训 VLA；48 小时完成一次单任务 A/B |

我的判断是：榜首不到 30%（预览榜）不是因为大家不会「看懂」，而是因为所有模型共享三个没有被利用的反馈通道：

1. **视角回声**：API 给了四路 RGB，官方 WLA 只用左头 + 两腕，右头是白送的第二个全局视角；VLA 又天然偏向腕部视角（FocusVLA 的实验结论）。单视角被遮挡、换背景、被人挡住时，策略没有第二个意见。
2. **关节回声**：API 给了 14 个手臂关节状态，官方 WLA 输出 EE；大多数队伍把关节状态只当观测，没把它当「接触传感器」。没有力/触觉，但关节跟踪误差本身就是扰动观测器的输入。
3. **原型回声**：33k 条成功演示不只是训练集，也是「下一步该怎么动」的运动基元库。R2A 已经证明，测试时检索运动基元可以在不微调 VLA 的情况下显著提升 OOD 鲁棒性。

所以本轮押注叫 **ECHO-LOOP**：

> **同一套动作意图，在四路视角上做一致性回声，在关节跟踪误差上做接触回声，在演示运动基元上做原型回声；三路回声的分歧用来触发 5 步闭环、切换视角、降低增益或重规划。VLA 仍是唯一学习模型，另外三路都是确定性控制器/检索器。**

一句话：**把「看见」升级成「看见 + 感到 + 记得」；不是再加一个模型，而是把 API 已经给的三路信号用起来。**

## 1. 先纠正上一轮的两个事实，再谈创新

### 1.1 腕部相机其实有内参，第 12 轮说「没有」是错的

第 12 轮写「腕部相机没有内参矩阵，必须先做一次标定」。本轮逐字段复核 HangCup 的 `meta/info.json`：

```text
wrist_left.color.camera_matrix  = [436.4058, 0, 323.9217; 0, 435.9215, 242.9332; 0, 0, 1]
wrist_right.color.camera_matrix = [435.1151, 0, 319.0249; 0, 434.4995, 240.9933; 0, 0, 1]
model = distortion.inverse_brown_conrady
```

也就是说，腕部 **color 相机有完整内参和畸变模型**；没有内参的是 IR1/IR2 的某些字段，不是 color。这个修正很重要：G0 从「标定腕部」降级为「验证腕部」，省下 3–5 天；多视角路由和腕部视觉伺服可以直接用现成内参。

来源：<https://huggingface.co/datasets/unitreerobotics/G1_Dex1_HangCup/raw/main/meta/info.json>（检索 2026-10-29）。

### 1.2 官方 WLA 只用三路图，右头根本没进模型

官方 `unitree.yaml` 的 `image_roles` 只有三个：

```yaml
image_roles:
  - "head_left"
  - "cam_wrist_left"
  - "cam_wrist_right"
```

`unitree_img_wo_stereo` 用 `head_stereo_left + wrist_left + wrist_right`；`unitree_img_with_stereo` 用 `head_stereo_left_rec + wrist_left + wrist_right`。**`head_stereo_right` 从未进入官方 WLA 的输入。** 这不是说官方错了；它说明右头是一个尚未被基线利用的、零成本的第二全局视角。

来源：<https://raw.githubusercontent.com/unitreerobotics/unifolm-wla/main/unifolm_wla/dataloader/multi_source_dataset/configs/unitree.yaml>（检索 2026-10-29）。

### 1.3 数据里其实有 joint action，关节空间不是「另起炉灶」

挑战赛数据每个 episode 同时提供：

- `observation.state.left_arm [7]`、`right_arm [7]`：当前关节位置；
- `action.left_arm [7]`、`action.right_arm [7]`：下一帧关节目标；
- `action.left_ee_pose_gripper_base [6]`、`right_ee_pose_gripper_base [6]`：EE 绝对位姿；
- `state_torso [6]`、`state_d435 [6]`、`waist_state_joint [3]`：腰部/头相机位姿标签；
- 四路 480×640 视频。

也就是说，**关节空间动作头和 EE 动作头都可以从同一批数据监督**；不需要 retargeting，也不需要额外采集。第 12 轮把「关节」只当观测，是浪费了 `action.left_arm` 这个直接监督信号。

来源：<https://huggingface.co/datasets/unitreerobotics/G1_Dex1_HangCup>（`features` 与首行样本，检索 2026-10-29）。

### 1.4 榜单仍是预览，不能把 29.7% 当 SOTA

2026-10-29 复核：

- 排行榜页显示「即将发布 Coming Soon」，表格为空；
- `leaderboard_data.json` 仍返回 8 个模型、32 个任务，`generated_from: "gen_leaderboard.py"`；8 个模型是 MolmoAct2 29.7 / WALL-OSS-0.5 28.5 / DreamZero 27.9 / Spirit-v1.5 25.9 / DM0 23.5 / PI-0.5 22.8 / GigaBrain-0 22.6 / GR00T N1.5 20.5；
- 详情页 32 个任务视频全部是「测试视频占位」；
- runs 页显示 256/256 条记录，成功率出现 25.1%、32.7%、38.2% 等非 10% 整数倍；每个任务只有 10 次 trial，真实成功率只能是 0/10、1/10、…、10/10；
- 对 8 个模型 ×32 任务做 `step ~ success` 回归，R² ≥ 0.9999996，最大残差 <0.006；跨模型任务级相关均值 0.0975。

结论：**29.7% 只能当「赛事方把上限压得很低」的难度信号，不能当实测 SOTA，也不能当任务难度表。** 但「所有模型都不到 30%」足以支持「共享执行/接触瓶颈」的判断。这个判断是本轮三个回声的共同前提。

来源：<https://unibot.unitree.com/leaderboard.html>、<https://unibot.unitree.com/leaderboard_data.json>、<https://unibot.unitree.com/runs.html>（检索 2026-10-29）。

## 2. 三个词的第一反应，以及我为什么砍掉一半

### 2.1 多视角：不要做「多视角大模型」，要做「多视角投票」

第一反应是「四路图一起进 VLA，训一个多视角融合模型」。我砍掉它的理由：

- 官方 WLA 的 VLM 是冻结的，输入槽位只有三个；加第四路要么改架构，要么再训一个融合器；
- 6B 模型每多一路图，推理和显存都涨；
- 单模型规则下，任何「再加一个融合网络」都要解释合规性；
- 真正缺的不是「更多像素」，而是「当一路视角被遮挡/换背景/被人挡住时，有没有第二意见」。

所以我不做融合器，做 **路由 + 投票**：同一 checkpoint，选两个视角子集各跑一次，把两个 30 步 chunk 对齐后取稳健中位数；分歧大就缩短执行块、切到视觉伺服或重规划。这是 test-time augmentation/ensemble，不是第二个模型。

外部证据：

- FocusVLA（arXiv:2610.31423，2026-10-22）发现现有 VLA「持续依赖腕部视角，缺乏跨阶段动态调整全局/局部视角的能力」，用阶段感知的多视角路由在 RoboTwin 2.0 上比 π0.5 高 10.10pp，真机 71.7%→85.0%；
- VersaCamVLA（arXiv:2610.12451，2026-10-08）用统一场景 token 支持任意数量/位姿的相机，说明「相机配置可变」是可学的；
- InfiNoVA（arXiv:2609.27734，2026-09-23）用 3DGS 生成新视角，在未见视角下成功率是未增强策略的 5.4 倍，说明视角多样性确实是瓶颈；
- StereoEngine（arXiv:2610.12734，2026-10-08）说明双目数据稀缺，但挑战赛恰好白送双目。

我的取舍：**先做零训练的视角路由 + 腕部互换，再做 view-dropout 微调，最后才考虑右头进 VLA。** 3DGS/NeRF 只作为离线增强候选，不进在线链路。

### 2.2 关节驱动：不要训关节 VLA，要做「关节执行 + 关节回声」

第一反应是「把动作头改成 joint，直接输出 14 维关节目标」。我砍掉它的理由：

- 官方 WLA 的 EE 动作头已经在 2500 小时、64 任务上预训练；改成 joint 等于丢掉这个先验；
- 关节空间跨任务泛化更差：Demystifying Action Space Design（arXiv:2602.23408，2026-02-26）在 13,000+ 真机 rollouts 上发现，joint space 和 task space 是互补的——joint 偏控制稳定性，task 偏泛化；
- 单模型规则下，再训一个 joint 策略风险高。

所以我保留 EE 意图，增加一个 **确定性关节执行层**：EE 30 步 plan → 解析 IK → 关节轨迹 → 限幅/限速/零空间姿态 → 下发 joint action。这样既拿到关节空间的平滑和限幅，又不丢 WLA 的语义泛化。

更关键的是第二层：**关节跟踪误差 = 无传感器接触回声**。API 没有力/触觉，但有关节指令和关节实测。低速自由空间里 `q_d − q_m` 很小；接触时它会变大。把它做成归一化分数 `c_t`，就能：

- 在接触段降低前馈速度/增益；
- 检测「人推了机器人」——视觉还没变化，关节已经先有反应；
- 检测滑移/卡住：`c_t` 持续高而物体没动；
- 触发 3 步短块，而不是继续开环 30 步。

外部证据：

- Demystifying Action Space Design 说明 joint space 对控制稳定性更友好，且 delta 动作一致更好；
- Impedance Cloning（arXiv:2609.30842，2026-09-25）用「刚度 + 平衡点」而不是轨迹做接触模仿，在 10 种杯子的 100 次试验中 84 次成功，固定阻抗基线 74/100；关键是它**不用力/力矩传感器**，用双边遥测的粒子滤波提取参数；
- ContactFlowFilter（arXiv:2610.29568，2026-10-21）用力/力矩传感器做本体接触估计，精度 0.36/0.88cm；我们没有力矩传感器，但可以用关节跟踪误差做弱化版；
- Kinematics-Aware Diffusion Policy（arXiv:2512.17568，2025-12-19）说明关节空间动作可以用运动学先验保证可行性。

我的取舍：**不做关节 VLA，不做力矩估计；只做「关节空间执行 + 跟踪误差门控」。** 如果 `c_t` 在真机上不可分，就退回视觉接触检测，关节层只保留平滑/限幅。

### 2.3 快速原型：不要做「32 个专用策略」，要做「任务卡 + 运动基元图」

第一反应是「每个任务快速搭一个专用策略」。这在规则上直接死掉：必须同一模型完成全部 32 个任务。

第二个反应是「快速搭一个仿真环境/数字孪生」。这有用，但不是本轮的重点；第 12 轮已经把数字孪生限定为控制器风洞。

我最终把「快速原型」落在两件事：

1. **PROTO-GRAPH**：把 33k 成功演示组织成运动基元图。节点是关键时刻的关节/EE 状态 + 多视角描述子；边是时间转移和跨 episode 的相似状态。测试时检索「下一步怎么动」，用置信度门控与 VLA 动作融合。新任务只需加演示和任务卡，不重训 VLA。
2. **PROTO-48**：每个任务一张机器可读的任务卡（对象、受器、成功谓词、阶段、接触类型、扰动轴、演示子集、安全限），48 小时内完成「建卡 → 建子图 → 离线回放 → 单任务通道 5 次 A/B → 更新组合」。

外部证据：

- R2A（arXiv:2610.37215，2026-10-27）把成功演示组织成时空运动基元图，测试时检索并与冻结 VLA 的动作做维度门控融合，在 LIBERO-Plus/RoboTwin2.0-Plus 上最高 +12%，真机 +40%，不需要微调；
- CapPro（arXiv:2610.19746，2026-10-14）用单条人类视频做 VLA 快速适配，说明「任务原型」不必是机器人轨迹；
- Optimus-R（arXiv:2609.39794，2026-09-30）用 query-skill memory 做技能复用，说明「记忆/原型」是 VLA 适配的活跃方向；
- PACE（arXiv:2606.00537，2026-05-30）说明执行 horizon 应该随阶段变化，固定 5 步未必最优。

我的取舍：**不做逐任务策略，不做在线大模型标注；只做非参数检索 + 确定性融合。** 如果官方认为「运动基元图 + 门控」算第二个模型，就退回 C1 模式：只用它离线生成阶段标签/评测集，不在线融合。

## 3. 诊断：三个「1 秒」之外，还有三个「单通道」

第 12 轮诊断的是三个「1 秒」：规划 1 秒、推理/网络 0.1–0.3 秒、恢复 1 秒。本轮再加三个「单通道」：

```text
单视角：  左头 + 两腕 → 一路意见；右头闲置；遮挡/换背景/人被挡 → 没有第二意见
单空间：  EE 绝对位姿 → 一路执行；关节状态只当观测；接触/人推 → 没有本体反馈
单策略：  VLA 从零泛化 → 一路动作；33k 演示只当训练集；OOD → 没有运动先验
```

三个「单通道」对应的失败模式：

| 失败模式 | 典型任务 | 单通道为什么失败 | 本轮对应 |
|---|---|---|---|
| 遮挡/背景/未见物品 | FruitSorting、ColorArrangement、OrganizeTools | 单视角外观偏移；VLA 过拟合腕部视角 | MV-ROUTE 视角投票 + 路由 |
| 插入/挂/叠/拉链/锁 | PlugInEthernet、HangCup、ZipUp、StackBowls、Unlock | EE 开环；接触发生在 chunk 内；无力/触觉 | JOINT-ECHO 跟踪误差 + 3/5 步短块 |
| 人为干扰 | human 轴 2/10 | 视觉变化有延迟；人推机器人时图像可能没变 | JOINT-ECHO 关节回声 + GEO-RESIDUAL 视觉编辑检测 |
| 长程/变形/语义 | FoldTowel、PackBag、SpellRobot | 运动基元不适用；VLA 仍是主力 | 保留 VLA；PROTO-GRAPH 只做先验 |

## 4. 方案：ECHO-LOOP

### 4.1 总架构

```text
Evaluator (N ports)
   │  obs: 4 RGB + 14 joints + 2 EE + 2 gripper + lower_body + language
   ▼
Per-port PolicyService (CPU)
   ├─ PROTO-48 task card / phase router
   ├─ MV-ROUTE: view subset selection + action agreement
   ├─ CHUNK-SERVO: 30-step plan, 5-step visual servo
   ├─ JOINT-ECHO: IK + joint trajectory + contact echo
   └─ Safety: joint limits, velocity, hold, max retries
   │  async, batched, same checkpoint
   ▼
Shared VLA server (GPU): UnifoLM-WLA-1.0, 30-step EE plan
```

- **唯一学习模型**：VLA（官方 WLA 微调 action head，可选 LoRA）。
- **确定性层**：视角路由/投票、IK/关节执行、接触回声、运动基元检索。
- **数据资产**：33k 演示 → 目标库（第 12 轮）+ 运动基元图（本轮）。
- **数字孪生**：只标定相机/关节/延迟/增益，不训练策略。

### 4.2 MV-ROUTE：让四路视角变成第二意见

三个子机制，按风险从低到高：

1. **腕部互换（零训练）**：同一 WLA，交换 `wrist_left`/`wrist_right` 槽位，得到两个 chunk；对齐后取中位数。适合腕部遮挡/反光。
2. **阶段路由（零训练）**：根据预测 chunk 的速度/接触概率，决定「看头」还是「看腕」：
   - 运输段（速度高、接触概率低）：头视图权重高；
   - 接触段（速度低、接触概率高）：腕部视图权重高；
   - 不确定段：两两组合，做一致性检查。
3. **视角 dropout 微调（低成本训练）**：训练时随机丢一路/换右头，让同一个 action head 见过多种视角组合；推理时才有资格做右头投票。

动作一致性：

```text
每个视角子集 k 输出 A_k = {a_{k,0}, ..., a_{k,H-1}}
位置：p* = geometric median({p_k})
姿态：R* = geodesic median({R_k})
分歧：D = mean_k ( ||p_k-p*||/σ_p + ||Log(R_k^T R*)||/σ_r )
若 D > τ_d：H_c ← 3；或切视觉伺服；或请求下一视角
```

关键：**投票发生在 30 步 plan 层，不发生在 5 步伺服层。** 这样不会把 VLA 推理翻倍到每个伺服块；30 步 plan 异步生成，5 步伺服用缓存 plan + 当前腕部图做确定性修正。

### 4.3 JOINT-ECHO：把关节跟踪误差变成接触/干扰回声

执行层：

```text
EE 30 步 plan → 绝对 EE 位姿 → 阻尼最小二乘 IK → 关节轨迹
             → 零空间姿态（肘部保持可操作）→ 限幅/限速/平滑
             → joint action (7+7) + gripper
```

接触层：

```text
e_q = q_d - q_m                 # 指令关节 - 实测关节
c_t = || W e_q ||,  W = 1/σ_i   # 自由空间标定
f_ext ≈ (J^T)^-1 K_q e_q        # 弱化版扰动观测器
若 c_t > θ_c：进入 CONTACT，降低前馈/增益，H_c ← 3
若 c_t 在运输段突增：疑似人推/碰撞，hold + 重定位
若 c_t 持续高且物体未动：疑似卡住/滑移，retreat + 重试
```

注意：API 没有力矩，`K_q` 是等效刚度，不是真实力；我们只用它做**相对变化**和**门控**，不报牛顿值。若真机上 `c_t` 不可分，就退回视觉接触检测，关节层只保留平滑/限幅。

### 4.4 PROTO-GRAPH：把 33k 演示变成「下一步怎么动」的先验

离线：

```text
对每个 episode 分段 → 关键帧节点（多视角描述子 + EE/关节状态 + 阶段）
                  → 时间边 + 跨 episode 相似边
                  → 每个任务一张子图；32 张子图共享索引
```

在线：

```text
检索 top-k 节点 → 沿图取未来 H 步运动基元
若距离 d < τ_d 且阶段匹配：
    a = (1-β) a_vla + β a_proto,  β = clip(σ((τ_d-d)/s), 0, 0.3)
否则 β=0，纯 VLA
```

与第 12 轮 DG-KEYFRAME 的区别：DG-KEYFRAME 检索「目标在哪」（相对位姿/目标图），PROTO-GRAPH 检索「下一步怎么动」（运动基元）。两者共享演示索引，不重复。

# 第 4 轮产物 · ECHO-LOOP 技术报告

> 检索/复核日期：**2026-10-29（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告承接第 12 轮 CHUNK-SERVO，研究线记为第 13 轮；不替换 FACT-VLA、GEO-RESIDUAL，而是把控制层从「单路视觉 + EE 伺服」升级为「多视角决策 + 关节空间执行 + 原型检索」。

## 0. 结论与边界

### 0.1 一句话结论

官方 WLA 的 30 步 EE chunk 已经解决了「语义→动作」的大部分问题；剩下不到 30% 的成功率，主要卡在三个单通道：**单视角、单空间、单策略**。本报告提出 **ECHO-LOOP**：同一套动作意图在四路视角做一致性回声（MV-ROUTE），在关节跟踪误差做接触/人为干扰回声（JOINT-ECHO），在 33k 演示的运动基元图做原型回声（PROTO-GRAPH）；三路分歧触发 3/5 步短块、视角切换、增益降低或重规划。VLA 仍是唯一学习模型，其余全部是确定性控制器/检索器。

## 2. 问题形式化

### 2.1 评分与不确定性

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

320 trials 下，若 `p≈0.25`：

```math
\mathrm{SE}(S)\approx \sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

配对 A/B 的方差取决于任务内相关；报告必须给配对差值的 bootstrap 置信区间，而不是只报两个平均值。

人为干扰轴：

```math
\Delta S_{\mathrm{human}} = \frac{2}{10}\,\Delta p_h = 0.2\,\Delta p_h.
```

即 human 轴成功率 +10pp → 全局 +2pp（每个任务 10 次里 2 次是 human；32 任务平均后仍为 0.2 倍）。

### 2.2 接口时间模型

```math
T_{\mathrm{fb}} \approx \frac{H_c}{f_c} + \tau.
```

| 场景 | `H_c` | `f_c` | `τ` | `T_fb` | 评价 |
|---|---:|---:|---:|---:|---|
| 官方 WLA 默认 | 30 | 30 | 50ms | **1050ms** | 接触段基本开环 |
| 本方案保守 | 5 | 30 | 50ms | **217ms** | 可做 1–2 次接触修正 |
| 本方案乐观 | 5 | 30 | 20ms | **187ms** | 需低 RTT |
| 本方案高延迟 | 5 | 30 | 150ms | **317ms** | 增益降档 |
| 低控制频率 | 5 | 10 | 50ms | **550ms** | 改 `H_c=3` 或只做 PBVS |
| 极低延迟 | 3 | 30 | 20ms | **120ms** | 动态任务可用 |

**结论**：`H_c` 必须按实测 `f_c` 和 `τ` 选；不能把 30 步默认值直接搬到远程 API。

### 2.3 三个单通道

```text
单视角：  左头 + 两腕 → 一路意见；右头闲置；遮挡/换背景/人被挡 → 没有第二意见
单空间：  EE 绝对位姿 → 一路执行；关节状态只当观测；接触/人推 → 没有本体反馈
单策略：  VLA 从零泛化 → 一路动作；33k 演示只当训练集；OOD → 没有运动先验
```

对应失败模式：

| 失败模式 | 典型任务 | 单通道为什么失败 | 本轮对应 |
|---|---|---|---|
| 遮挡/背景/未见物品 | FruitSorting、ColorArrangement、OrganizeTools | 单视角外观偏移；VLA 过拟合腕部视角 | MV-ROUTE 视角投票 + 路由 |
| 插入/挂/叠/拉链/锁 | PlugInEthernet、HangCup、ZipUp、StackBowls、Unlock | EE 开环；接触发生在 chunk 内；无力/触觉 | JOINT-ECHO 跟踪误差 + 3/5 步短块 |
| 人为干扰 | human 轴 2/10 | 视觉变化有延迟；人推机器人时图像可能没变 | JOINT-ECHO 关节回声 + GEO-RESIDUAL 视觉编辑检测 |
| 长程/变形/语义 | FoldTowel、PackBag、SpellRobot | 运动基元不适用；VLA 仍是主力 | 保留 VLA；PROTO-GRAPH 只做先验 |

### 2.4 为什么是现在

- **API 白送四路 RGB 和 14 个关节状态**，但官方基线只用了三路图和 EE 动作。
- **33k 成功演示**已经存在，既能训 action head，也能建目标库/运动基元图。
- **官方 WLA 6B 基座 + 24GB 微调**把「大模型」这件事做完了；边际收益在控制/接口。
- **近期工作**证明多视角路由（FocusVLA）、运动基元检索（R2A）、阶段化执行（PACE）、关节空间动作（Demystifying Action Space）都是活跃方向，但还没有人把它们组合成「单模型合规 + 远程 API + 32 任务」的方案。

## 3. 方法：ECHO-LOOP

### 3.1 总架构

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)       │
                    │  ├─ PROTO-48 task card / phase      │
                    │  ├─ MV-ROUTE (view select + vote)   │
                    │  ├─ CHUNK-SERVO (30-step plan)      │
                    │  ├─ JOINT-ECHO (IK + contact echo)  │
                    │  └─ Safety (limits/hold/retry)      │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared VLA server (GPU)            │
                    │  UnifoLM-WLA-1.0, 30-step EE plan   │
                    └─────────────────────────────────────┘
```

- 每个端口一个 `PolicyService` 实例，独立 `reset()`、独立 plan cache、独立 phase/echo 状态。
- 视角投票/检索/IK 是 CPU 线程，不阻塞 websocket；VLA 请求异步、可批处理。
- 共享 VLA server 用 session ID 区分端口；模型权重只有一份，不违反单模型。

### 3.2 MV-ROUTE：多视角决策

#### 3.2.1 三个子机制

| 子机制 | 训练成本 | 作用 | 风险 |
|---|---|---|---|
| 腕部互换 | 0 | 左/右腕互为备份；抗遮挡/反光 | 模型可能分不清左右腕 |
| 阶段路由 | 0 | 运输看头、接触看腕；减少无效视角 | 阶段判断错 |
| 视角 dropout 微调 | 低 | 同一 action head 见过多种视角组合；右头可用 | 单视角回归 |
| 动作一致性投票 | 0 | 两个 chunk 对齐取中位数；分歧做不确定性 | 推理翻倍 |

#### 3.2.2 视角配置

API 四路图映射到 WLA 三槽：

| 配置 | head 槽 | wrist_left 槽 | wrist_right 槽 | 用途 |
|---|---|---|---|---|
| V0（官方） | left head | left wrist | right wrist | 基线 |
| V1（腕互换） | left head | right wrist | left wrist | 腕部遮挡/反光 |
| V2（右头） | right head | left wrist | right wrist | 第二全局视角 |
| V3（双头+单腕） | left head | right head | left wrist | 运输段几何 |
| V4（双头+右腕） | left head | right head | right wrist | 运输段几何 |

训练时对每个样本采样一个配置（view dropout），至少保留 1 个全局视角 + 1 个腕部视角；缺失槽位用黑图/复制替代。推理时按阶段选 2 个配置，异步跑同一 checkpoint。

#### 3.2.3 阶段路由

用预测 chunk 的速度和接触回声定义阶段分数：

```math
s_t = \frac{\lVert a_t-a_{t-1}\rVert}{\Delta t},\qquad
c_t = \text{JOINT-ECHO contact score}.
```

- 运输段：`s_t` 高、`c_t` 低 → 头视图权重高（0.6–0.8）。
- 接触段：`s_t` 低、`c_t` 高 → 腕部视图权重高（0.6–0.8）。
- 不确定段：`s_t` 中、`c_t` 中 → 头+腕各一，做一致性检查。

权重不用学习，用分段函数/softmax：

```math
w_{\text{head}} = \sigma\!\left(\frac{s_t-s_0}{s_1}\right)\,(1-c_t),\qquad
w_{\text{wrist}} = 1-w_{\text{head}}.
```

选择 top-2 视角时加多样性约束：不能两个都是同一类（除非另一类全部无效）。

#### 3.2.4 动作一致性

对每个视角配置 `k`，得到 30 步 chunk `A_k`。在 EE 空间对齐（绝对位姿）或关节空间对齐（关节目标）：

```math
p^* = \arg\min_p \sum_k w_k \lVert p-p_k\rVert,\qquad
R^* = \arg\min_R \sum_k w_k \lVert \mathrm{Log}(R_k^\top R)\rVert^2.
```

位置用几何中位数（Weiszfeld），姿态用测地线中位数（迭代切空间平均）。分歧：

```math
D = \frac{1}{K}\sum_k \left(
\frac{\lVert p_k-p^*\rVert}{\sigma_p} +
\frac{\lVert \mathrm{Log}(R_k^\top R^*)\rVert}{\sigma_r}
\right).
```

门控：

- `D ≤ τ_d`：正常执行 5 步。
- `τ_d < D ≤ τ_h`：`H_c ← 3`，并降低伺服增益。
- `D > τ_h`：hold，请求下一视角/重规划；若连续 3 次，回退单视角 VLA。

#### 3.2.5 训练细节

- 冻结 VLM（`qwen_vl_interface`），只训 DiT action head + robot-state projector；可选 LoRA。
- 数据：32 个挑战数据集，按 session/物体/背景分组划分；相邻帧不跨 split。
- 图像 resize 到 WLA 的 336×448；训练时随机视角 dropout（p=0.3–0.5）。
- 动作目标保持官方 EE 相对动作；不改成 joint（joint 由执行层 IK 生成）。
- 先跑 1–2 个 epoch 的 view-dropout 微调；若单视角回归 >3pp，回退原始 checkpoint 并只做零训练路由。

### 3.3 JOINT-ECHO：关节空间执行 + 接触回声

#### 3.3.1 执行层

```text
EE 30 步 plan (absolute) → 阻尼最小二乘 IK → 关节轨迹
                        → 零空间姿态（肘部可操作）→ 限幅/限速/平滑
                        → joint action (7+7) + gripper
```

- 用官方 G1 29-DoF MuJoCo XML 的关节顺序/限位/力矩范围；7-DoF 手臂：shoulder pitch/roll/yaw、elbow、wrist roll/pitch/yaw。
- IK 用阻尼最小二乘 + 零空间姿态；关节限位用 barrier；速度/加速度用保守上限。
- 输出绝对关节目标（与 API `joint` 模式一致）；gripper 单独标定。
- 如果 IK 失败/接近奇异，回退 EE 动作（`control_space` 不能中途切换，所以在部署时二选一；单任务通道先验证 joint 模式）。

#### 3.3.2 接触回声

```math
e_q = q_d - q_m,\qquad
c_t = \lVert W e_q\rVert_2,\quad W=\mathrm{diag}(1/\sigma_i).
```

`σ_i` 从自由空间标定。弱化版扰动观测器：

```math
f_{\text{ext}} \approx (J^\top)^{-1} K_q e_q.
```

`K_q` 是等效关节刚度，不是真实力矩；只用相对变化/门控，不报牛顿值。

状态机：

| 条件 | 判定 | 动作 |
|---|---|---|
| `c_t ≤ θ_c` | 自由空间 | 正常前馈 |
| `θ_c < c_t ≤ θ_h` | 预接触/轻接触 | 降速 30–50%，`H_c ← 5` |
| `c_t > θ_h` | 硬接触/碰撞 | hold 2–3 帧，`H_c ← 3`，切视觉伺服低增益 |
| `c_t` 在运输段突增 | 人推/碰撞 | hold + 重定位；视觉确认 |
| `c_t` 持续高且物体未动 | 卡住/滑移 | retreat 1–2cm，重试/重抓 |
| `c_t` 高后骤降，夹爪闭合 | 滑移 | 加大夹持/重抓 |

#### 3.3.3 关节空间柔顺

不试图估计真实力；用跟踪误差做**阻抗整形**：

```math
q_d' = q_{\text{nom}} - \gamma e_q,\qquad 0<\gamma<1.
```

- 接触段 `γ` 增大（更柔顺），运输段 `γ→0`（更跟踪）。
- 法向/切向分解需要笛卡尔方向；用 `J^{-T}` 把 `e_q` 映射到笛卡尔，再分解。
- 不做法向力闭环；只做「别推太狠」和「别继续开环」。

#### 3.3.4 人为干扰

- 人推机器人：`c_t` 突增，视觉可能没变 → 关节回声先触发 hold。
- 人移动物体：`c_t` 不变，视觉编辑检测（GEO-RESIDUAL）触发重定位。
- 两者互补；不声称 100% 检测。

### 3.4 PROTO-GRAPH：运动基元图

#### 3.4.1 离线建图

```text
for each episode:
    phases = segment(episode)                  # 速度/接触/夹爪事件
    for each keyframe k:
        z_k = [φ(I_views), p_ee, q, phase]     # 多视角描述子 + 本体
        node = (task, phase, z_k, A[k:k+H])
    edges = temporal + kNN cross-episode
```

- `φ` 用 ORB/颜色直方图/深度轮廓等确定性描述子；不用第二个学习模型。
- 每个任务一张子图；32 张子图共享索引。
- 节点存 `H=5` 步关节轨迹/EE 轨迹，便于在线融合。
- 规模：33,276 episodes × 1–2 关键帧 ≈ 20–40k 节点；128×128 缩略图 + 描述子 <1GB。

#### 3.4.2 在线检索与融合

```text
candidates = graph[task].filter(phase=current_phase)
topk = candidates.knn(z_t, k=5)
if topk[0].distance < τ_d and phase consistent:
    a_proto = topk[0].future_H
    β = clip(σ((τ_d - d)/s), 0, β_max)
    a = (1-β) a_vla + β a_proto
else:
    a = a_vla
```

- `β_max=0.3`，避免运动基元压过 VLA 语义。
- EE 动作在 SE(3) 上融合；关节动作在关节空间融合。
- 阶段/任务过滤优先于外观；不要让颜色直方图把「插网线」匹配到「拔网线」。
- 与 DG-KEYFRAME 的区别：DG-KEYFRAME 检索「目标在哪」，PROTO-GRAPH 检索「下一步怎么动」。

#### 3.4.3 快速原型：PROTO-48

任务卡字段：

```yaml
task_id, name, instruction
objects, receptacle, success_predicate
phases: [reach, grasp, align, insert, release]
contact_type: insert|hang|stack|zip|pour|deform|none
perturbations: [position, distractor, background, unseen_object, human]
demo_dataset, keyframes, primitives
safety: {max_joint_vel, max_force_proxy, max_retries}
```

48 小时时钟（已有演示）：

| 时段 | 动作 | 产出 |
|---|---|---|
| 0–6h | 建卡、选演示、标阶段 | task card v1 |
| 6–18h | 建子图、离线回放、仿真扰动 | 检索 top-5 / 失败分类 |
| 18–30h | 接入 PolicyService、单元测试 | 可跑的单任务服务 |
| 30–42h | 单任务通道 5 次配对 A/B | servo/joint/proto on/off |
| 42–48h | 分析、更新组合、决定 keep/kill | 组合权重 |

### 3.5 与 CHUNK-SERVO 的集成

```text
每 30 步（1s）：
  MV-ROUTE 选 2 个视角 → 同一 VLA 异步出 2 个 30 步 EE plan
  → 对齐/中位数 → D 门控 → 得到 plan

每 5 步（167ms）：
  plan[t:t+H_c] → EE 前馈
  + 视觉伺服（相对目标，来自 DG-KEYFRAME）
  + JOINT-ECHO（IK/限幅/接触门控）
  → joint action chunk (H_c, 7+7) + gripper + pivot=0
```

- VLA 只在 plan 层跑；5 步层不跑 VLA。
- 视角投票只在 plan 层；5 步层用当前视角做确定性伺服。
- 关节回声在每个 5 步块内更新；触发时缩短下一块。

## 4. 关键推导

### 4.1 多视角动作一致性

设 K 个视角配置，第 k 个输出 `A_k = {(p_{k,t}, R_{k,t}, g_{k,t})}_{t=0}^{H-1}`。

位置几何中位数：

```math
p_t^* = \arg\min_p \sum_{k=1}^K w_k \lVert p-p_{k,t}\rVert_2.
```

Weiszfeld 迭代：

```math
p^{(r+1)} = \frac{\sum_k w_k p_{k,t}/\lVert p^{(r)}-p_{k,t}\rVert}
{\sum_k w_k/\lVert p^{(r)}-p_{k,t}\rVert}.
```

姿态测地线中位数：

```math
R_t^* = \arg\min_R \sum_k w_k \lVert \mathrm{Log}(R_{k,t}^\top R)\rVert^2.
```

迭代：

```math
R^{(r+1)} = R^{(r)}\mathrm{Exp}\!\left(
\frac{\sum_k w_k \mathrm{Log}(R^{(r)\top}R_{k,t})}{\sum_k w_k}
\right).
```

分歧：

```math
D_t = \frac{1}{K}\sum_k w_k\left(
\frac{\lVert p_{k,t}-p_t^*\rVert}{\sigma_p} +
\frac{\lVert \mathrm{Log}(R_{k,t}^\top R_t^*)\rVert}{\sigma_r}
\right).
```

`σ_p, σ_r` 用干净验证集的视角间标准差标定；`τ_d` 取 90–95 分位。

### 4.2 视角路由

```math
s_t = \lVert p_t-p_{t-1}\rVert/\Delta t,\qquad
c_t = \lVert W e_q\rVert.
```

```math
w_{\text{head}} = \sigma\!\left(\frac{s_t-s_0}{s_1}\right)(1-c_t),\qquad
w_{\text{wrist}} = 1-w_{\text{head}}.
```

- `s_0` 取演示速度中位数；`s_1` 取 IQR。
- 选择 top-2 时，若 `w_head` 和 `w_wrist` 都接近 0.5，强制一头一腕。
- 视角置信度可用图像清晰度/遮挡分数（经典指标）加权；不用学习模型。

### 4.3 关节空间 IK

位姿误差：

```math
e = \begin{bmatrix} p_d-p \\ \mathrm{Log}(R_dR^\top) \end{bmatrix}\in\mathbb R^6.
```

阻尼最小二乘：

```math
\Delta q = J^\top(JJ^\top+\lambda^2 I)^{-1}e
+ (I-J^\top(JJ^\top+\lambda^2 I)^{-1}J)\Delta q_{\text{null}}.
```

零空间：

```math
\Delta q_{\text{null}} = k_p(q_{\text{null}}-q) - k_l\nabla\phi_{\text{lim}}(q).
```

- `q_null` 选择肘部弯曲、腕部朝下的可操作姿态。
- `φ_lim` 是关节限位 barrier；`λ` 随奇异值自适应。
- 积分后 clip 到 URDF 限位；速度/加速度限制；低通。

### 4.4 关节接触回声

低层控制器近似：

```math
\tau = K_q(q_d-q_m)+D_q(\dot q_d-\dot q_m)+\tau_{\text{ff}}.
```

外部扰动：

```math
\tau_{\text{ext}} = \tau - M(q)\ddot q - C(q,\dot q)\dot q - g(q).
```

无力矩传感器时，用稳态近似：

```math
\tau_{\text{ext}}\approx K_q(q_d-q_m).
```

归一化：

```math
c_t = \left\lVert \mathrm{diag}(1/\sigma_i)(q_d-q_m)\right\rVert_2.
```

低通：

```math
\bar c_t = \alpha \bar c_{t-1}+(1-\alpha)c_t.
```

门限 `θ_c, θ_h` 用自由空间 99 分位和接触验证集 ROC 选；`σ_i` 按关节分别标定。

**限制**：`K_q` 未知且可能时变；`c_t` 不是力，只是跟踪误差。若低层控制器高刚度，`e_q` 可能很小；此时改用关节速度残差 `\dot q_m-\dot q_d` 或视觉接触检测。G9 先验证可分性，再决定是否上线。

### 4.5 关节空间柔顺

```math
q_d' = q_{\text{nom}} - \gamma\,\mathrm{sat}(e_q/\epsilon)\,e_q.
```

- `sat` 限制单步修正；`γ` 随 `\bar c_t` 增大。
- 笛卡尔分解：

```math
f_{\text{ext}}\approx (J^\top)^{-1}K_q e_q,\qquad
f_n = n^\top f_{\text{ext}},\quad f_t = (I-nn^\top)f_{\text{ext}}.
```

- 法向缩幅/低通；切向保留。
- 不闭环力；只做「接触即减速/停止/退让」。

### 4.6 运动基元融合

```math
d = \lVert z_t-z_i\rVert_M,\qquad
\beta = \mathrm{clip}\!\left(\sigma\!\left(\frac{\tau_d-d}{s}\right),0,\beta_{\max}\right).
```

```math
a = (1-\beta)a_{\text{vla}}+\beta a_{\text{proto}}.
```

- `M` 是描述子/位姿/关节的块对角权重；任务/阶段硬过滤。
- `β_max=0.3`；`d>τ_d` 时 `β=0`。
- 旋转在切空间融合：`R = R_{\text{vla}}\mathrm{Exp}(\beta \mathrm{Log}(R_{\text{vla}}^\top R_{\text{proto}}))`。

### 4.7 延迟/算力预算

| 组件 | 频率 | 延迟（目标） | 备注 |
|---|---|---:|---|
| VLA 单次 | 每 30 步 | 100–300ms | 6B，4 步去噪 |
| MV-ROUTE 双视角 | 每 30 步 | 200–600ms | 可异步/批处理；plan TTL 1s |
| 视觉伺服 | 每 5 步 | 5–20ms | CPU/经典几何 |
| IK + 关节轨迹 | 每 5 步 | <1ms | 7-DoF，warm start |
| 关节回声 | 每步 | <1ms | 低通/阈值 |
| 运动基元检索 | 每 30 步 | 1–5ms | kNN/DTW |
| 端到端伺服 | 每 5 步 | 167ms + RTT | `H_c=5` @30Hz |

### 5.2 `get_action` 伪代码

```python
class EchoLoopPolicy:
    def get_action(self, obs):
        self._tick(obs)

        # 1) plan layer: async VLA + multi-view vote
        self._maybe_request_plan(obs)
        if self.plan is None:
            self.plan = self._safe_plan(obs)   # cold start, sync, timeout hold
            self.plan_idx = 0

        # 2) phase / view routing
        phase = self.task_card.phase(self.plan, obs, self.echo)
        views = self.mv_route.select(phase, obs, self.echo)

        # 3) 5-step block
        H = self.H_c
        a_ff = self.plan[self.plan_idx:self.plan_idx + H]
        if len(a_ff) < H:
            a_ff = np.concatenate([a_ff, np.repeat(a_ff[-1:], H-len(a_ff), 0)])

        # 4) visual servo (relative target from DG-KEYFRAME)
        delta = self.servo.compute(obs, self.goal, phase)

        # 5) joint execution + contact echo
        q_d = self.ik.solve(compose(a_ff, delta), obs)
        q_d = self.joint_safety(q_d, obs)
        q_d, hold = self.echo.gate(q_d, obs, phase)

        # 6) prototype prior (optional, bounded)
        if self.proto is not None and not hold:
            q_d = self.proto.blend(q_d, obs, phase)

        self.plan_idx += H
        if self.plan_idx >= len(self.plan):
            self.plan = None

        return self.adapter.to_api(q_d, obs, self.token)
```

### 5.3 动作适配

#### EE 模式

```text
WLA 54D:
  left_ee_rel[6], left_gripper[1], left_hand[6],
  right_ee_rel[6], right_gripper[1], right_hand[6],
  waist[3], torso[3], base_vxvy[2], base_wz[1],
  base_pose_rel[6], height[1], left_leg[6], right_leg[6]

挑战赛 ee 21D:
  left_ee_abs[6], right_ee_abs[6],
  left_gripper[1], right_gripper[1], pivot[7]
```

映射：

1. `left_ee_abs = compose(T_base_ee_left_current, exp(left_ee_rel))`；转 xyz+rpy。
2. `right_ee_abs` 同理。
3. gripper 直通（范围需标定）。
4. `pivot` 先返回全零；语义验证后再映射。
5. 腿部/灵巧手在 `ee` 模式下不直接下发。

**关键细节**：WLA 的每个未来动作是「相对 plan-time 当前 EE」的位姿，不是累积增量；adapter 必须先把整个 30 步 compose 成 base 系绝对目标，再按 5 步切片。否则第 6–30 步会以错误锚点解释，产生系统性偏移。

#### Joint 模式

```text
EE 绝对目标 (H,6) → IK (H,7) → 关节限幅/平滑 → action.left_arm/right_arm (H,7)
```

- 用 warm start；上一块的最后一帧作为下一块初值。
- 关节顺序按 API/URDF 验证；符号错误会导致肘部翻转。
- gripper 与 pivot 同 EE 模式。
- 如果 IK 失败率 >1%，回退 EE 模式（提交前二选一）。

### 5.4 状态机

```text
INIT ──first obs──▶ PLAN ──plan ready──▶ SERVO
  ▲                   ▲                    │
  │                   │                    ├─ D > τ_d ──▶ VOTE/HOLD
  │                   │                    │
  │                   │                    ├─ c_t > θ_c ──▶ CONTACT
  │                   │                    │                 │
  │                   │                    │                 └─ released ──▶ SERVO
  │                   │                    │
  │                   └── replan ◀── RECOVER ◀── edit/echo spike
  │                                      │
  └──────────────────────────────────────┘
任意状态 ──task success / max steps──▶ DONE
```

- `VOTE/HOLD`：视角分歧大；请求下一视角或重规划。
- `CONTACT`：关节回声高；降速/缩短块/柔顺。
- `RECOVER`：人推/视觉编辑；hold → 重定位 → 重规划。
- `DONE`：清理状态，等待 `reset()`。

### 5.5 安全

- 关节限位留 5% 余量；速度/加速度保守。
- 接触回声触发 hold 时，不做大幅回撤；先停 2–3 帧。
- 最大重试 3 次；失败则安全 hold/退回。
- 每端口独立；共享 VLA server 不共享 episode 状态。
- 记录每步延迟、`c_t`、视角分歧、IK 残差；异常时降级。

| PROTO-48 | 1 人周 + 2 周运营 | 加速迭代；不直接涨点 | 必做 |
| 完整世界模型 | 8+ GPU 周 | 不确定；延迟更差 | 不做 |
| 32 任务各训策略 | 规则禁止 | — | 不做 |

收益算术：

- A 档 12 任务各 +10pp → `12/32×10=+3.75pp`；
- B 档 10 任务各 +5pp → `10/32×5=+1.56pp`；
- human 轴 +10pp → +2pp（20% 权重）；
- 保守合计 +4–7pp；乐观 +8–10pp；
- 这些是设计目标，不是承诺；G6/G9 不过就不提交。

## 8. 创新点清单（第 4 轮版）

> 状态：**KEEP**=本轮主投；**MERGE**=并入其他点；**EVAL**=只做评测工具；**PRUNE**=本轮不做。每个点给动机、与现有方案差异、可行性、资源、落地步骤、风险。

### K1 · MV-ROUTE（KEEP，主投）

- **动机**：API 四路 RGB；官方 WLA 只用左头 + 两腕；VLA 过拟合腕部视角（FocusVLA）；单视角在遮挡/换背景/人为干扰下没有第二意见。
- **与现有方案差异**：不是多视角融合大模型，也不是在线 3DGS；是同一 checkpoint 的视角路由 + view-dropout + 动作中位数投票。与 ANCHOR-ICP 的「右眼做深度」不同，MV-ROUTE 把右眼变成第二个决策者；两者可叠加。
- **技术可行性**：高。官方 WLA 支持 3 图输入/微调；挑战赛数据四路图齐全；动作是 EE 绝对/相对，容易对齐；视角投票是 test-time augmentation，不违反单模型。
- **所需资源**：1–2 GPU 周（action-head 微调）；1 名工程师 2 周；四路图数据；plan 层 2× 推理（可异步/批处理）；CPU 侧路由/中位数。
- **落地步骤**：G0 内参/对极 → 腕互换零训练 A/B → view-dropout 微调 → 视角分歧 AUROC → 5 任务 A/B → 全量干跑。
- **风险**：单视角回归（回退原始 checkpoint）；双视角延迟（限制在接触/高不确定段）；右头域偏移（先腕互换，后右头）；合规解释（同一权重，多次前向）。

### K2 · JOINT-ECHO（KEEP，最高上限）

- **动机**：API 给 14 个关节状态；无力/触觉；接触密集任务是主要失败模式；关节跟踪误差是免费的本体信号；人推机器人时视觉可能没变。
- **与现有方案差异**：不是纯 joint VLA，也不是力矩估计；是「EE 意图 + 解析 IK + 关节空间执行 + 跟踪误差门控」。与 CHUNK-SERVO 的 EE 伺服互补：视觉说「往哪」，关节回声说「碰到了/被推了」。
- **技术可行性**：中。G1 29-DoF XML/关节限位可得；IK 成熟；关节跟踪误差在低层控制器下是否可分需 G4 验证；若不可分，退回视觉接触检测。
- **所需资源**：1 名工程师 2–3 周；G1 URDF/MuJoCo；1 GPU 周；单任务通道；关节状态 30Hz；无需新传感器。
- **落地步骤**：G0 FK/IK → 关节限位/平滑 → 自由空间 `c_t` 标定 → 接触/人推 AUROC → 5 任务 A/B → 安全审查。
- **风险**：高刚度控制器让 `e_q` 太小（用速度残差/视觉兜底）；关节顺序/符号错（G0）；IK 奇异（DLS/零空间/回退 EE）；接触时误停（阈值/迟滞）；合规（确定性控制器）。

### K3 · PROTO-GRAPH（KEEP，次投）

- **动机**：33k 成功演示是运动基元库；R2A 证明检索可提升 OOD 且无需微调；新任务加演示即可，不重训。
- **与现有方案差异**：不是学习 GNN/第二个模型；是确定性 kNN/DTW + 置信度门控。与 DG-KEYFRAME 检索「目标位姿」不同，PROTO-GRAPH 检索「未来 H 步动作」。
- **技术可行性**：高。离线建图 CPU 可做；索引 <1GB；在线 kNN 1–5ms；与 VLA 动作融合简单；风险是匹配错，用任务/阶段硬过滤 + β 上限。
- **所需资源**：1 名工程师 2 周；33k 演示；CPU/内存；<1GB 存储；无需 GPU。
- **落地步骤**：分段/关键帧 → 多视角描述子 → 子图 → 检索评测 → 融合 A/B → OOD 测试。
- **风险**：外观相似但语义不同（任务/阶段过滤）；描述子脆弱（多视角 + 本体）；合规（非参数记忆/确定性融合；必要时只离线用）。

### K4 · PROTO-48（KEEP，工程加速）

- **动机**：32 任务/320 trials；需要快速建卡、评测、决定 keep/kill；单任务通道是唯一敢做 A/B 的地方。
- **与现有方案差异**：不是新模型；是任务卡 + 48h 闭环 + 组合权重；把「快速原型」落在软件/任务层，不改硬件。
- **技术可行性**：高。任务卡 schema 简单；32 个数据集已有；单任务通道可用；瓶颈是人工标阶段/建卡。
- **所需资源**：1 名工程师 1 周搭工具 + 2 周运营；32 张卡；单任务通道配额；无 GPU。
- **落地步骤**：schema → 8 张卡试点 → 自动化脚本 → 48h 循环 → 更新组合。
- **风险**：标注成本（先做 A 档 8 个）；单任务通道过拟合（配对/重复）；时间（48h 是目标，不是保证）。

### K5 · VIEW-DROPOUT（MERGE → K1）

- **动机**：让同一 action head 见过缺视角/换右头/腕互换。
- **差异**：数据增强，不改架构；不是新模型。
- **可行性**：高；官方微调支持；只需改 dataloader。
- **资源**：并入 K1 的 GPU 周。
- **步骤**：采样视角掩码 → 训练 → 单视角/多视角评测。
- **风险**：单视角回归；掩码分布与真机不符。**状态：并入 K1，不单独立点。**

### K6 · JOINT-SYNERGY（MERGE → K2）

- **动机**：7-DoF 冗余；PCA/DCT 低维关节协同；零空间姿态避免肘部翻转。
- **差异**：确定性降维/姿态优化，不是学习策略。
- **可行性**：高；演示关节轨迹可做 PCA；IK 零空间成熟。
- **资源**：并入 K2。
- **步骤**：PCA/DCT → 零空间 → 限幅/平滑。
- **风险**：降维丢失接触修正自由度；只用于姿态先验，不限制修正。**状态：并入 K2。**

### K7 · PHASE-HORIZON（MERGE → CHUNK-SERVO）

- **动机**：PACE 证明执行 horizon 应随阶段变化；固定 5 步未必最优；接触段要短，运输段可长。
- **差异**：训练-free 的 3/5/8 选择；由速度/接触/视角分歧共同决定。
- **可行性**：高；但 API `action_chunk_size` 固定，运行时不能改；只能在提交前选一个值，或用内部 plan 切片模拟。
- **资源**：并入 CHUNK-SERVO。
- **步骤**：离线扫 3/5/8 → 选固定值 → 内部按阶段切片。
- **风险**：API 限制；固定值折中。**状态：并入 CHUNK-SERVO，不单独立点。**

### K8 · FAIL-CARD（EVAL）

- **动机**：320 trials 需要失败分类/反事实回放；否则不知道涨点来自哪。
- **差异**：评测工具，不是策略。
- **可行性**：高；任务卡 + 失败标签 + 视频回放。
- **资源**：1 人周；存储。
- **步骤**：失败 taxonomy → 自动打标 → 反事实回放 → 组合更新。
- **风险**：标签主观；只做方向性分析。**状态：EVAL，低优先级。**

### P1 · 从零训通用 VLA/World Model（PRUNE）

- 理由：官方 WLA 6B + 2500h 已做完；算力/数据不划算；边际收益低于执行层。

### P2 · 力/触觉/IMU 硬件（PRUNE）

- 理由：API 没有；不能改硬件；关节回声是替代方案。

### P3 · 逐任务策略/逐任务微调（PRUNE）

- 理由：规则要求同一模型；32 个策略不泛化；单任务通道只用于评测，不用于提交多模型。

### P4 · 在线 3DGS/NeRF/SAM2（PRUNE，离线候选）

- 理由：显存/延迟/合规；InfiNoVA 的离线增强可考虑，但不进在线链路。

### P5 · 把预览榜单当任务难度表（PRUNE）

- 理由：`gen_leaderboard.py` 生成；R²≈1；非 10% 整数倍；跨模型相关 0.0975；只能当弱先验。
