# 第 41 轮 · 数据面与信用账本 v18：从「步数经济学」到「分数学」（中间件＝评测即采集，数据集＝部分分缺口，四层架构 v6）

> 承接第 40 轮（v17：Δ 资源平面 × 步数感知规划 × 学习-TO 混合轨迹）。本轮灵感词「中间件 / 数据集」。初看是基础设施词，不像创新点；但把它们放回官方提交协议下审视后，发现它们恰好戳中 v17 的一个**口径错误**：v17 把榜单的「步骤分」当成动作步数来省，而公开榜单历史快照显示步骤分是 **rubric 部分完成度**（模型级 `step ≈ 0.510 + 1.321·success`，R²=0.981；逐任务仿射 `b` 均值 1.334、R² 均值 0.9925、最小 0.9715，且 256 个 (任务,模型) 点上 `step < success` 的违例为 0），并且公开数据集只有成功示范、没有子目标/失败标签。于是 v18 的主轴从 v17 的「单位物理成本的得分效率」进一步校正为 **「可验证的部分分最大化」**：中间件负责把评测变成带标签的数据（Σ 数据面），数据集负责补 rubric 部分分与失败样本（覆盖地图），规划器负责「不丢已得分」（信用账本）。

## 0. 事实与实测（先事实后推理；检索/快照口径 2026-11-10，实验产物见 exp/r41_mwdata/）

- **事实 F67（公开训练语料，HF datasets-server 缓存 2026-11-02）**：32 个任务 `unitreerobotics/G1_Dex1_*` 共 **33,276 episodes**（每任务 969–1533）；缓存行的 37 字段 schema 只有 state/action/time/frame/episode/task，**没有 success、subgoal、rubric、failure 标签**。与 F61（挑战赛专用 split 页面 401）不矛盾：**训练语料公开、挑战评测 split 门控**——这正好把「数据从哪来」和「评测长什么样」分成两个可独立处理的问题。
- **事实 F68（榜单历史快照 2026-11-04，8 个公开模型）**：平均成功率 20.5–29.7、平均步骤分 28.1–39.0；模型级 `step = 0.510 + 1.321·success`（R²=0.981）；逐任务仿射 `b∈[1.19,1.40]`、均值 1.334、R² 均值 0.9925、最小 0.9715；全部 256 点相关系数 0.9977，逐任务残差标准差仅约 0.6 分。→ **「步骤分」几乎不是独立轴，而是 rubric 部分分，且当前没有模型在利用它与成功率的残差。**
- **事实 F69（官方任务 rubric，任务页 info.json 快照）**：每任务 2–5 个 rubric 子目标、权重和为 100（2 步:11 个任务、3 步:14、4 步:5、5 步:2）。这给出**数据集的缺失标签模式**：子目标权重与顺序。
- **事实 F70（覆盖统计）**：公开 episodes 数与任务平均成功率相关仅 r=0.217，与模型间 spread 相关 0.219；23/32 任务有「未见物体」评测注记、30/32 有「人为干扰」注记，但公开数据几乎全是名义成功示范——**缺的不是 episode 数量，是负例/部分分标签**。
- **事实 F71（本轮实测，检索证伪）**：在 15 个任务、k=8 的缓存真实行上，跨 episode 最近邻动作块检索相对零阶保持（ZOH）的中位增益 **−281.2%**（相位对齐 −348.6%，相位条件均值 −373.1%），**0/15 任务为正**，检索胜率中位数 0.04/0.024/0.013。原因不神秘：30fps 动作自相关极高，ZOH 误差 ~σ√(2(1−ρ)) 远小于跨 episode 的相位/场景差异。→ **数据面不能缓存动作，只能检索抽象。**
- **事实 F72（本轮实测，评测设计）**：per-task 成功率代理的 σ∈[0.382,0.460]、变异系数 3.6%，Neyman 分配相对均匀分配的方差降幅 ≤0.1%；M=1280（40/任务）→ SE=1.21pp、两模型 95% 差异分辨约 3.36pp；M=2560 → SE=0.856pp、分辨约 2.37pp；要检测 1pp 需约 14,403 episodes、2pp 约 3,601、0.5pp 约 57,610。→ **小规模本地榜无法分辨 <3pp；必须配对/共用随机数，别追噪声。**

## 1. 研究者直觉（先直觉与动机，后形式化）

**直觉 1（中间件不是管道，是取证仪器）。** 官方提交的本质是「评测端作为 client，通过 websockets 调我们的 PolicyService」。这意味着：策略与评测分布之间唯一合法的观察点，就是我们的服务进程。v16/v17 把这一层当控制面（路由、熔断、节流），却漏了它的另一半——**数据面**：每一次 `get_action` 的观测、动作、时延、守卫结果、`reset()` 边界，都可以在本地结构化落盘。评测对我们是黑盒，但**经过我们的每一帧不是黑盒**。于是「评测即采集」：把线上评测流变成带 provenance 的 episode ledger，再把 ledger 变成影子评测与训练集。这不是日志，而是**把不可见的官方分布变成可测量对象**的取证层——而且零接口改造成本。

**直觉 2（数据集的问题不是量，是标签口径）。** 33,276 条示范听起来很多，但 schema 里没有「成功/失败」、没有「rubric 子目标」、没有「泛化轴」标签。而官方评分恰恰是 rubric 部分分（F68/F69）。也就是说：**我们有 33k 条轨迹，却没有一条能直接监督「我现在拿到了多少分、下一步别把分丢掉」**。真正稀缺的是「部分分曲线」与「失败/近失败」样本，而不是更多名义成功示范。F70 的 r≈0.217 也说明：在同一任务内堆 episode 的边际收益很低，缺的是**轴上的覆盖**与**负例**。

**直觉 3（v17 的「步数」是误读，必须当轮纠错）。** v17 的 IP-49 把 `g(N_steps)` 当目标，试图少走动作步。但 F68 显示公开榜的步骤分与成功率近似仿射（b=1.334，R²=0.9925），而 rubric 是子目标权重（F69）。所以「步骤分」是**部分完成度**，不是动作计数。动作计数是**成本**（吃热、吃时延、吃机会），部分分是**奖励**。把两者混在一个 `g(N)` 里，会让规划器为了省动作而放弃已完成/可完成的子目标——恰好丢掉最容易拿的分。v18 必须把它们拆开：**成本账本（热/时延/动作数）与奖励账本（rubric credit）分离**。

**直觉 4（显著性陷阱：盲榜 + 小本地集 = 噪声放大器）。** F72 给了一个冷酷的算术：40 episodes/任务只能把两模型差异分辨到约 3.4pp。若我们每轮靠 1–2pp 的本地提升做决策，等于在噪声里调参。正确做法不是盲目加大到 1.4 万 episode（太贵），而是**配对设计**：同一任务/场景/随机种子下跑 A/B，用共同随机数把方差摁下去，并报告置信区间；同时把「步骤分残差」作为独立信号，而不是把 `step` 与 `success` 双重计数。

**直觉 5（检索抽象，不检索动作）。** F71 是一次干净的证伪：跨 episode 找最近邻动作块，连「保持当前动作」都打不过。结论不是「数据没用」，而是**索引的粒度错了**：数据面应该检索 `(任务, 技能, 相位, 子目标, 约束, 失败签名)` 这类抽象，而不是 dense action。这个负结果直接决定了 IP-51 的索引设计，也避免我们重蹈 v17 隐含的「动作缓存」假设。

## 2. 灵感词 → 落地线（新增 + 重构 + 修剪登记）

- 「**中间件**」→ **IP-51 DATA-PLANE-MIDDLEWARE（Σ-Plane，P0 新增）**：episode ledger（append-only、per-port 隔离、fail-open）+ 数据契约/provenance + 抽象索引（task/skill/phase/subgoal/constraint/failure，**不存动作块**）+ 影子评测总线（协议忠实、N 端口、chunk 语义、配对随机数）+ 时延/动作统计自审计（对齐 F60 可信度条款）。
- 「**数据集**」→ **IP-52 COVERAGE-CARTOGRAPHER（DATA-DIET，P0 新增）**：五轴（未见物体/位置/背景/干扰物/人为干扰）覆盖地图；`w_t=(100−success_t)·spread_t/√n_t` 的采集权重（实测 top-8 占 34.5%、top-16 占 62.3%）；失败/近失败与 rubric 部分分样本的主动采集；污染防火墙（门控评测数据永不入训练）。
- 「**中间件×数据集**」→ **IP-53 CREDIT-LEDGER-RECOVERY（P0 新增，重构 IP-49）**：把 `C_t=Σ_j w_j·1[子目标 j 达成]` 作为奖励账本；恢复必须**信用单调**（不撤销已得子目标）；动作数是成本不是目标；用 CTC + VLM + 技能分段估计 `Ĉ_t` 并做单调滤波（isotonic/累计最大 + 迟滞）。
- **升级**：IP-28v2（CTC 进度 → rubric credit 曲线）、IP-30（VLM 判别 → 子目标部分分）、IP-48（Δ-Plane 加第 4 个奖励账户 `C_t`；`S_used` 仅作成本）、IP-25（SLO 加 shadow-eval 口径）、IP-36（语义图挂 rubric 子目标锚点）、IP-50（TO 热启动吃 credit 阶段的参考）。
- **修剪登记（规则 51）**：**IP-42 CROSS-EMBODIMENT-MOTION → P2**（官方单本体 G1，跨本体不计分，属于能力展示型）；**IP-44 PROGRESSIVE-CURRICULUM-DISTILL → P2**（当前瓶颈是标签/覆盖，不是蒸馏，数据/算力门槛高、边际得分低）。复杂度预算换给数据面与信用账本。

## 3. 形式化直觉（严格版见产物区 §3）

**定义 29（Rubric credit 过程）**：任务 τ 有子目标 `g_1..g_m` 与权重 `w_j≥0, Σw_j=100`；`C_t=Σ_j w_j·1[g_j 在 t 前达成]`，`R=C_T`（步骤分），`S=1[R=100]`。榜单 `J=αS+βR`（α,β 未公开，A39）。经验：`R≈0.510+1.321S`（R²=0.981），逐任务 b=1.334、R²=0.9925。**独立信号是残差** `R−(a+bS)`（实测逐任务残差标准差仅约 0.6 分），而不是把 S 与 R 重复计分。

**定义 30（信用单调恢复）**：恢复策略须满足 `P(C_{t+1}<C_t)≤ε`；动作数 `Σ1` 只进成本约束 `E[cost]≤B`。规划/恢复目标：`max_π E[C_T] s.t. 信用单调 + 成本约束`。这取代 v17 的 `max Πp_s·g(N_steps)`（把成本误当奖励）。

**定义 31（数据面 Σ）**：`Σ: (obs_t, chunk, latency, guard) ↦ (ledger, Ĉ_t, provenance)`；三条硬性质：(a) **fail-open**（Σ 永不阻塞 `get_action`）；(b) **per-port 隔离**（`reset()` 清空，端口间无共享可变状态）；(c) **provenance/污染防火墙**（`source∈{public_demo,self_collect,shadow,gated_eval}`，gated 不入训练/索引）。

**定义 32（覆盖与采集）**：`P_eval=Σ_a π_a P_a`（五轴），`gap_a=∫|p_eval,a−p_data,a|`；采集 `max_{|D'|≤B} ΔE[C_T]`，用 `w_t=(100−success_t)·spread_t/√n_t` 的一阶近似（实测 top-8=34.5%，top-16=62.3%）。

**定义 33（抽象检索）**：检索键 `κ=(task_id, skill_id, phase_bin, subgoal_id, scene_hash)`，值 `{约束, 名义参数, 失败签名, 示范统计}`；**禁止**把 dense action chunk 作为检索值（F71 证伪：ZOH 已优于跨 episode 动作检索）。

## 4. 关键决断

1. **口径纠错优先**：先做 E73（rubric 审计）再写任何代码；若 F68 的口径不成立，立即退回 v17 的成功率主轴。
2. **成本/奖励分账**：Δ-Plane 从三账本扩为「三成本 + 一奖励」；动作数只作成本，rubric credit 才是奖励。
3. **数据面是唯一取证点**：中间件必须 fail-open、per-port 隔离、provenance；不碰官方协议，不做动作缓存。
4. **检索抽象**：只索引子目标/技能/相位/约束/失败签名；动作块检索被 F71 否决。
5. **评测经济学**：本地 shadow-eval 用配对/共同随机数；<3pp 的差异默认当噪声，除非 M≥1280 且 CI 支持。

## 5. 本轮最大风险（一句话）

**若官方「步骤分」并不是 rubric 部分分（公开快照的 `step≈0.51+1.32·success` 只是模型同质化造成的巧合），则本轮把规划目标建在错误口径上——所以 E73 必须先于一切实现；一旦 E77 的 rubric 标注一致性（单调性/κ）不达标，IP-53 立刻退回成功率单目标，只保留数据面的日志与覆盖图。**

# 第 41 轮产物 · 创新点清单 v18：数据面中间件 × 覆盖数据集 × 信用账本（「分数学」横切层，四层架构 v6）

> 承接 v17（第 40 轮）。本轮灵感词「中间件 / 数据集」经公开快照与本轮实测（口径 2026-11-10）后，发现 v17 存在一个必须先修的**评分口径错误**：榜单的「步骤分」不是动作步数，而是 rubric 部分完成度（公开快照 `step ≈ 0.510 + 1.321·success`，R²=0.981；逐任务 b=1.334、R²=0.9925；残差标准差仅约 0.6 分）。因此 v18 新增 **2 项数据面 IP（IP-51 数据面中间件 / IP-52 覆盖采集器）+ 1 项信用账本 IP（IP-53，重构 IP-49）**，把架构主轴从「单位物理成本的得分效率」校正为 **「可验证的部分分最大化」**；并修剪 2 项能力展示型设计（IP-42 跨本体、IP-44 渐进蒸馏 → P2）。

## 0. 结论

- **口径纠错（本轮总纲）**：F68/F69 表明「步骤分 = rubric 部分分」，不是动作计数。v17 的 `g(N_steps)` 目标把**成本**当**奖励**，会让规划器为省动作而丢子目标分。v18 把 Δ-Plane 扩为「三成本（热/时延/动作数）+ 一奖励（rubric credit `C_t`）」，`S_used` 仅作成本。
- **IP-51 DATA-PLANE-MIDDLEWARE（P0 新增，Σ-Plane）**：官方 `PolicyService` 是评测分布经过我们代码的唯一合法观察点。构建 append-only episode ledger + 数据契约/provenance + 抽象索引（子目标/技能/相位/约束/失败签名，**不缓存动作块**）+ 协议忠实的影子评测总线（N 端口、chunk 语义、配对随机数）+ 时延/动作统计自审计。三条硬性质：fail-open、per-port 隔离、污染防火墙。
- **IP-52 COVERAGE-CARTOGRAPHER（P0 新增，DATA-DIET）**：五轴覆盖地图 + `w_t=(100−success_t)·spread_t/√n_t` 的采集权重（实测 top-8 占 34.5%、top-16 占 62.3%）+ 失败/近失败/部分分样本的主动采集 + 门控数据污染防火墙。核心判断：公开语料 33,276 episodes 的缺口是**标签**（无 success/subgoal/failure），不是数量（episodes 与 success 相关仅 0.217）。
- **IP-53 CREDIT-LEDGER-RECOVERY（P0 新增，重构 IP-49）**：`C_t=Σ_j w_j·1[子目标 j 达成]`；规划目标 `max E[C_T]`，动作数进成本约束；恢复必须**信用单调**（不撤销已得子目标）；`Ĉ_t` 用 CTC + VLM + 技能分段估计并做单调滤波。这直接利用 F68 的残差空档——当前没有模型在利用「成功之外的 partial credit」。
- **修剪（规则 51）**：IP-42 CROSS-EMBODIMENT-MOTION → P2（单本体 G1，跨本体不计分）；IP-44 PROGRESSIVE-CURRICULUM-DISTILL → P2（标签/覆盖优先于蒸馏）。
- **本轮实测四件事**（全部在 `exp/r41_mwdata/`）：E73 rubric 审计（b=1.334、R²=0.9925、0 违例）；E74 影子评测定容（40/任务仅能分辨 ~3.4pp）；E75 覆盖/采集权重（top-8=34.5%）；E76 检索证伪（动作块检索中位增益 −281.2%，0/15 任务为正）。
- **诚实记录**：A39 官方步骤分公式未公开，本轮按「rubric 部分分」高置信推断；A40 公开行 schema 无 success/subgoal 字段（已核对 37 字段）；A41 检索探针只含 proprio/action、每任务约 3k 帧，结论严格限定为「proprio-only dense action retrieval」被证伪；A42 榜单快照为 2026-11-04 历史数据，当前站点显示 Coming Soon，二者不冲突。

## 1. 事实卡（F67–F72；全部来自公开快照或本地产物）

- **F67（公开训练语料）**：`unitreerobotics/G1_Dex1_<Task>` 32 个任务，HF datasets-server 缓存（2026-11-02）共 **33,276 episodes**（min 969 / max 1533）；行 schema 37 字段 = `observation.state.*` / `action.*` / `timestamp` / `frame_index` / `episode_index` / `index` / `task_index`，**无 success、subgoal、rubric、failure 字段**。与 F61（挑战赛专用 HF split 401）地位不同：**训练语料公开，评测 split 门控**。
- **F68（榜单历史快照，2026-11-04，8 模型）**：平均成功率 20.5–29.7、平均步骤分 28.1–39.0；模型级 `step = 0.510 + 1.321·success`（R²=0.9814）；逐任务仿射 `mean_b=1.334`（min 1.19 / max 1.40）、`mean_r2=0.9925`（min 0.9715）；全部 256 点 `corr=0.9977`、逐任务残差标准差均值 0.627；`step < success` 违例 **0**。→ 步骤分是 rubric 部分分，且与成功率强耦合；独立残差只有约 0.6 分。

### 3.2 IP-51 DATA-PLANE-MIDDLEWARE（数据面中间件，完整设计）

**IP 卡片（六字段）**：
- **动机**：官方评测是远程 `PolicyService` 调用（F60）；服务进程是评测分布的唯一合法观察点。v16/v17 只做了控制面（路由/熔断/节流），没有把「经过我们的数据」变成可测量对象；同时榜单盲、挑战 split 门控（F61），本地必须自建取证与影子评测。
- **与现有方案差异**：常见方案把 serving 当纯推理入口；我们把它同时当**数据采集仪器 + 影子评测总线 + 抽象索引服务**。不缓存动作（F71 证伪），只检索抽象。
- **技术可行性**：websockets/msgpack/JPEG 协议已由官方模板给出；ledger 用 JSONL/Parquet 异步写；抽象索引用小规模向量库/SQLite；影子 client 复用官方 example 协议；无接口改造。
- **所需资源**：盘 8h×N 端口 ledger（压缩后 <10GB）；CPU 侧索引/查询 <1ms；影子评测复用本地 GPU 与公开数据。
- **落地步骤**：① 实现 fail-open ledger + 数据契约；② per-port 隔离与 reset 语义；③ 抽象索引（先用 rubric/技能分段）；④ 影子评测总线（N 端口、配对种子）；⑤ 时延/动作统计自审计；⑥ E79 压测。
- **风险**：日志 I/O 抖动（→有界队列 + drop-oldest + fail-open）；磁盘满（→配额 + 滚动）；污染（→provenance 防火墙）。

**数据契约（最小 schema）**：
```
EpisodeRecord = {
  schema_version, episode_id, port_id, task_id, split ∈ {train,val,shadow,gated_eval},
  provenance ∈ {public_demo,self_collect,shadow,gated_eval},
  t, obs_hash, scene_hash, action_space ∈ {joint,ee}, chunk_len,
  latency_ms, guard_flags[], credit_curve[], rubric_version
}
IndexKey = (task_id, skill_id, phase_bin, subgoal_id, scene_hash)
IndexValue = {constraint_set, nominal_params, failure_signatures, demo_stats}   # 不含 action chunk
```
**fail-open / 隔离算法**：
```
on get_action(obs):
  try:
    rec = build_record(obs)                 # O(1)，只做引用/哈希
    ledger_q.put_nowait(rec)                # 有界队列；满则 drop_oldest
  except Exception:
    pass                                    # 绝不阻塞/抛出
  state = port_state[port_id]               # 每端口独立 EpisodeState
  action = policy(obs, state)
  try: ledger_q.put_nowait(action_meta(action))
  except Exception: pass
  return action
on reset(port_id):
  port_state[port_id] = EpisodeState(...)   # 只清本端口
```
**正确性论证**：P51（fail-open）——记录路径只有 O(1) 入队/哈希，异常被吞；`get_action` 最坏情况退化为无记录。P52（隔离）——所有可变 episode 状态按 `port_id` 分片，`reset()` 仅替换本片；全局只有只读模型权重。P53（不泄漏）——索引与训练写入前过滤 `source=gated_eval`，并按 `scene_hash`/`episode_id` 去重。

**已知风险**：异步写盘在极端 I/O 下仍可能造成 p99 抖动——E79 以「关闭/阻塞 logger」双盲压测；若 p99 增量 >1ms，降级为离线 replay 记录。

### 3.3 IP-52 COVERAGE-CARTOGRAPHER（覆盖采集器，完整设计）

**IP 卡片（六字段）**：
- **动机**：公开语料 33,276 episodes 但无 success/subgoal/failure 标签（F67），且 episode 数与成功率弱相关（r=0.217，F70）；评测沿五轴偏移，缺的是轴覆盖与负例。
- **与现有方案差异**：不是「多采数据」，而是**按覆盖缺口 + 头部空间 + 异质性**采；并把 rubric 子目标作为标签 schema（F69）。加入门控数据污染防火墙。
- **技术可行性**：五轴可用视觉嵌入/物体目录/位姿分布/接触事件做代理度量；采集权重是闭式；子模贪心有 1−1/e 保证。
- **所需资源**：自采/仿真失败样本（E77/E78）；公开数据的 rubric 对齐弱标注；少量人工抽检。
- **落地步骤**：① 定义五轴代理度量；② 建覆盖矩阵；③ 计算权重并贪心排期；④ 生成失败/近失败/部分分样本；⑤ 训练 credit 验证器；⑥ E75/E77 验收。
- **风险**：覆盖度量误设（→双样本分类器 AUC + 人工抽检）；仿真失败样本不真实（→真机小样本校准）；污染（→provenance）。

**五轴与代理度量**：

| 轴 | 评测变化 | 数据覆盖代理 | 采集动作 |
|---|---|---|---|
| A1 物体 | 未见物体/材质/颜色 | 物体目录/视觉嵌入的两样本可分性 | 新物体×同任务重放 |
| A2 位置 | 物体/容器位置移动 | 位姿分布 MMD | 位置网格采样 |
| A3 背景/光照 | 桌面/背景/灯光变化 | 图像嵌入域分类 AUC | 背景/光照增广 |
| A4 干扰物 | 额外物体/遮挡 | 场景图物体计数/包络 | 加干扰物重放 |
| A5 人为干扰 | 人移动物体/语言变体 | 接触/位移事件 + 指令槽位 | 扰动注入 + 恢复对 |

**采集权重**（E75 实测）：
```
w_t = (100 − mean_success_t) · spread_t / sqrt(n_t)
```
- top-8 任务占 34.5%，top-16 占 62.3%——采集应集中而非撒胡椒面。
- top-8：HangCup 5.25%、RemovePinnedNote 4.59%、StackBowls 4.53%、OrganizeStationery 4.34%、Unlock 4.20%、PlacePhotoFrame 4.09%、PlugCharger 3.78%、PackDoll 3.69%。
- 关键反直觉：`episodes` 与 `mean_success` 仅 0.217、与 `spread` 仅 0.219 → **再堆名义 episode 不划算**。
- 子模贪心：`max_{|D'|≤B} Σ_{t,a} w_{t,a}(1−e^{−n_{t,a}/κ})`，边际收益递减，1−1/e 保证。

**正确性论证**：P54（覆盖贪心）——覆盖函数单调子模，贪心达 1−1/e；P55（采集效率）——权重按 headroom×heterogeneity/√n 排序，单位 episode 的期望 credit 增益递减；P56（污染隔离）——`gated_eval` 标签在写入前被过滤，训练/索引不可见。

### 3.4 IP-53 CREDIT-LEDGER-RECOVERY（信用账本恢复，完整设计）

**IP 卡片（六字段）**：
- **动机**：F68 显示当前模型把 `R` 几乎完全绑定到 `S`（残差仅 ~0.6 分）；这意味着「失败但保住部分分」是公开榜上未被利用的空档。F69 给出子目标权重，使 credit 可定义、可弱监督。
- **与现有方案差异**：v17 最小化动作数；v18 最大化 rubric credit，并把恢复约束为**信用单调**。失败后不是「从零重试」，而是「保住已得子目标，再争取剩余」。
- **技术可行性**：CTC 进度（IP-28v2）+ VLM 子目标判别（IP-30）+ 技能分段（v16 的 IP-27/分段器）可融合成 `Ĉ_t`；单调滤波（isotonic / 累计最大 + 迟滞）防止误判回退；规划仍是 beam，目标换成 `E[C_T]`。
- **所需资源**：rubric 弱标签（E77）、失败/恢复对（E78）、credit 验证器；算力与 v17 规划器同量级。
- **落地步骤**：① 用 rubric+技能分段给公开示范打子目标标签；② 训练/校准 credit 估计器；③ 加单调滤波；④ 规划目标改 `E[C_T]`；⑤ 恢复加入信用单调约束；⑥ E78 A/B。
- **风险**：credit 估计误差（→只用于恢复/停止，不用于急停；阈值保守）；reward hacking（→完成奖金、禁止主动终止、E78 守成功率）；rubric 口径错（→E73 先行）。

**符号表**：`g_j` 子目标；`w_j` 权重（Σ=100）；`C_t=Σ_j w_j·1[g_j done]`；`Ĉ_t` 估计；`ε` 允许的信用回退；`B` 动作/热/时延成本预算；`R_safe(Ĉ_t)` 不减少信用的恢复动作集。

**信用估计与单调滤波**：
```
Ĉ_raw(t) = Σ_j w_j · σ( f_j(o_{0:t}) )        # f_j: CTC 进度 + VLM 子目标判别 + 技能段
Ĉ(t)     = max_{s≤t} Ĉ_raw(s)                  # 累计最大（或 isotonic 拟合）
若 Ĉ_raw(t) < Ĉ(t−1) − δ 且证据强：
    记录 credit_loss 事件；阈值 δ 防止单帧噪声
```

**规划 / 恢复算法**：
```
输入：指令 l、观测 o、当前 credit Ĉ_t、账本成本、场景画像 σ
主规划（reset 后一次）：
  beam search 最大化 E[C_T | π] − λ·E[cost(π)]
  # 注意：动作数只进 cost，不再乘进 g(N)
执行中：
  若 failure_monitor ∨ Ĉ_t 停滞 > Tw ∨ 证书违约：
      R_safe = { r ∈ RecoverySkills | 预测执行 r 后 C ≥ Ĉ_t − ε }
      若 R_safe ≠ ∅：选 argmax_{r∈R_safe} E[C_T | r]
      否则：保守策略（保当前子目标，尝试最高剩余权重子目标）
      # 禁止「从零重试」这类会撤销已得子目标的动作，除非明确收益 > 损失
输出：技能序列 + 每段 prosody/预算提示
```
**正确性论证**：P57（信用非回退）——在 `R_safe` 内执行，`C` 不下降（按定义）；P58（部分分占优）——同一成功率下，`E[C_T]` 更高者在 `J=αS+βR`（α,β>0）下不劣；P59（不牺牲成功）——`R_safe` 排除会撤销子目标的动作，因此不以成功率换信用；主策略仍以 `E[C_T]` 为目标，成功是 `C=100` 的特例。

**例子**：StackBowls（rubric [30,30,40]）叠好两个后第三个失败 → 不去碰倒已叠的两个（保住 60），再尝试第三个；HangCup 挂失败 → 先保持杯子在夹爪（保住已得步骤）而不是松手；PackDoll 关盖失败 → 保住娃娃在盒内。

```python
    # 2. credit 估计 + 单调滤波
    raw = credit_verifier(obs, port_state.history)          # Σ_j w_j σ(f_j)
    port_state.C = max(port_state.C, raw)                   # 单调
    # 3. 主规划或信用恢复（动作数只进 cost）
    if port_state.need_plan:
        port_state.plan = credit_planner(
            obs.language, semantic_map, credit=port_state.C,
            p_s=port_state.p_s, W=port_state.gwm,
            cost_budget=delta_plane.cost_budget())
    if failure_monitor(obs) or stalled(port_state.C):
        safe = [r for r in recovery_skills(obs)
                if predict_credit_after(obs, r) >= port_state.C - EPS]
        if safe:
            port_state.skill = argmax_expected_credit(safe)
        else:
            port_state.skill = secure_highest_remaining_subgoal(obs)
        data_plane.log_event("credit_recovery", port_state.C, port_state.skill)
    # 4. 执行（v17 的 TO/流式/CBF 不变）
    chunk = execute_skill(port_state, obs)                  # IP-50/43/33
    return chunk

# ===== 影子评测总线（IP-51，协议忠实 + 配对设计）=====
def shadow_eval(policy, tasks, n_per_task, seeds):
    for task in tasks:
        for s in seeds:                       # 配对：同一 seed 跑 A/B
            ep = replay(task, seed=s)         # 公开数据/仿真/真机
            log = run_policy_service(policy, ep, ports=N)   # 8765.. 端口
            score = {**success(log), **rubric_credit(log)}
            ci = bootstrap_ci(score, n_per_task)
```

## 6. 清单迭代规则（继承 27–51 + 本轮新增 52–55）

- 继承规则 27–51（通道诚实/映射验证/SLO/fail-safe/灵感-现实校验/单模型合规/步骤分双解释/稠密监督/方法论遗产/元数据重照亮/语言口径分离/摊销/验证器分级/灵感词落地/层级联合规划/跨本体运动/流式韵律/渐进蒸馏/服务化/证书化/组合代数/热预算/期望得分/学习-TO/修剪优先）。
- **52（新增）：数据面取证原则**——评测经过服务进程的每一帧都是可采集数据；ledger 必须 append-only、fail-open、per-port 隔离、带 provenance；数据面不得改变控制路径。
- **53（新增）：覆盖优先原则**——采集按 `gap×headroom×heterogeneity` 排序，不按名义 episode 数量；门控评测数据永不入训练/索引（污染防火墙）。
- **54（新增）：信用单调原则**——奖励是 rubric credit `C_t`，成本是热/时延/动作数；恢复不得撤销已得子目标；动作数只进成本约束，不乘进目标。
- **55（新增）：显著性纪律原则**——本地 A/B 必须配对/共同随机数并报告 CI；M<1280 或差异 <3pp 时不得据此做架构决策；步骤分与成功率近似共线，报告残差而非重复计分。

**本轮最大风险一句话**：**若官方「步骤分」并非 rubric 部分分（F68 的 1.33× 仿射只是模型同质化的巧合），则本轮的信用账本会把规划目标建立在错误口径上——E73 必须先于一切实现，E77 的标注一致性不达标时 IP-53 立即退回成功率单目标。**

**当前最值得押注**：**IP-53 CREDIT-LEDGER-RECOVERY（信用账本恢复）**——F68 的残差只有约 0.6 分，说明公开榜上「失败但保住部分分」几乎是空白；rubric 权重公开（F69），credit 可弱监督、可 E78 用配对 A/B 在一个实验里证实/证伪。IP-51 提供取证与影子评测，IP-52 提供缺失的失败/部分分样本；三者形成「采集→标注→恢复→验证」的闭环，而不是再堆一个能力展示模块。
