## 0. 本轮先核实：六个改变判断的事实

### 0.1 排名规则比上一轮理解的更“成败论”

官方参赛手册（中文 [S2]、英文 [S3]）把之前模糊的地方写清楚了：

- 每个任务独立跑 **10 次**，5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰）**每类各 2 次**；
- 单次真机执行上限 **180 秒**，超时记为失败，并按执行情况给步骤分；
- 实时榜单**按 32 个任务的总平均成功率排序**；成功率相同才看总平均步骤分；再相同，提交日期早的靠前；
- 只有“单模型 + 全 32 任务”进榜；单任务测试通道不计分。

这纠正了上一轮的一个隐含偏差：PILOT 用“终局步骤占 39.8% 步骤分”来论证放置优先，但**步骤分只是平分决胜，不是第一目标**。真正该看的是“哪些步骤是成功闸门”。这并不意味着放置不重要，而是说：**首步和终步都是闸门，不能只攻出口。**

### 0.2 榜单：前三名在统计上几乎不可区分，而且当前数据仍是占位

榜单页现在能看到 8 条记录，榜首 MolmoAct2/DexHacker 为 **29.7% / 39.0**，第二 WALL-OSS-0.5 为 **28.5% / 38.9**，第三 DreamZero 为 **27.9% / 37.9**（[S4][S5]）。但必须同时说清楚：

- `leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`（[S5]）；
- `details.html` 的每个任务视频仍写着“测试视频占位，后续可替换为真实视频文件”（[S7]）；
- 页面底部仍出现“即将发布 / Coming Soon”（[S4]）。

所以我把这 8 条当成**官方基线/占位先验**，不当作真实赛果，更不用它判断谁强谁弱。即便假设数字是真的，前三名只差 **1.8pp**；在 320 次计分试次、p≈0.3 下，总体标准误约 **2.56pp**（√(0.3×0.7/320)），1.8pp 不到 1 个 SE。**换句话说：ARM、VLA、WAM 三种范式在榜首的差距落在噪声里，继续换底座很难是第一位的问题。**

### 0.3 评分算术：首步 35.5% + 终步 39.8% = 75.3%，首步被上一轮低估了

我把 32 个任务的 `info.json` 全部重新抓取并解析（[S8]；本轮共 32 个文件，满分合计 3200）：

| 位置 | 分值 | 占比 | 含义 |
|---|---:|---:|---|
| 首步 | 1135 / 3200 | **35.5%** | 任务的第一道成功闸门 |
| 中间步 | 790 / 3200 | 24.7% | 多对象/多阶段任务的过渡 |
| 终步 | 1275 / 3200 | **39.8%** | 任务成功的最后一道闸门 |
| 合计 | 3200 | 100% | 32 任务 × 100 分 |

首步再按动作类型拆：

| 首步类型 | 任务数 | 首步分值 | 占比 | 例子 |
|---|---:|---:|---:|---|

| 放置/放入/堆叠/收纳（place/put/stack/pack/store） | 10 | 355 | 11.1% | T03 装娃娃、T20 放纸杯、T27 放碗 |

| 合计 | 32 | 1135 | 35.5% | — |

还有两个结构性事实：

- **11 个任务是两步任务**（T01、T02、T03、T05、T08、T14、T19、T23、T24、T30、T32），合计 1100 分（34.4%）。它们本质上就是“一个抓取/接触 + 一个放置/闭合”的配对；如果抓取-放置联合做对，这 11 个任务直接受益。
- 16 个任务的第一动作是显式抓取/夹持。抓取不是“前置动作”，而是**入场券**；抓错部位，后面的放置再准也没用（抓杯身挂不上杯架、抓插头线插不进插座、抓拉链布合不上拉链）。

### 0.4 头部方案：三种范式，共同的“接触层”短板

把榜单前三当作三个公开模型家族来分析（仍然提醒：UniBot 分数是占位先验）：

- **MolmoAct2 / DexHacker（ARM，29.7%）**：Ai2 的 Action Reasoning Model，VLM 先产出空间轨迹，再由 action expert 出动作；公开博客自己列了两条弱点：**一次规划 10–30 步、整段开环执行，中途遇到障碍/扰动不会重新推理**；以及**只在 SO-100、双臂 YAM、Franka 上充分训练，换人形/换手需要额外数据**（[S15]）。这正好对应 UniBot 的 G1 + Dex1 + 人为干扰。
- **WALL-OSS-0.5 / Generalist Robotics（VLA，28.5%）**：4B VLA，3B VLM 底座，20+ 形态、每 epoch 超百万轨迹，强调“预训练即可在真机执行”，15 任务真机套件平均任务进度 60.5%，比 π0.5 高 17.5pp（[S16][S17]）。但“跨形态预训练强”不等于“G1 + Dex1 的接触正确”；插座、拉链、杯柄这些局部几何仍要专门补。
- **DreamZero / World Model Lab（WAM，27.9%）**：14B 视频扩散世界动作模型，Wan2.1-I2V-14B 底座，7Hz 闭环，DROID 单臂数据为主，强调新任务/新环境泛化和 30 分钟少样本适配（[S18]）。视频先验有利于“会发生什么”，但 14B 的延迟、单臂数据与 G1 双臂/Dex1 的形态差，都会在接触精度上打折。

三者分数 29.7 / 28.5 / 27.9，差距 1.8pp。**这不是“谁的网络更好”的差距，而是同一个接触层瓶颈的三种表现。** 占位数据里 MolmoAct2 最差的几个任务也很有提示性：Disconnect Ethernet 21.3%、Unlock 23.5%、Pick Out Battery 23.5%、Place Photo Frame 24.3%、Organize Pencil Case 25.0%、Fold Towel 27.2%、Hang Cup 27.3%——几乎都是“抓对部位 + 精细接触/闭合”，而不是自由空间搬运。**再次强调：这些任务级数字是占位数据，只能用来生成假设，不能当结论。**

### 0.5 数据与接口：终于可以认真做“度量抓取”了

- 数据集 collection 现在有 32 个数据集、**33,276 条 episode**（官方页写 32k；HF 实际 33,276），每任务 969–1,533 条；HangCup 1,043 条、194,564 帧、30fps（[S9][S10][S11]）。
- 四路相机：左右高位 stereo + 左右腕部，640×480；状态含双臂 7 维关节、EE 位姿（base/torso 两套）、夹爪开度、下肢 15 维；`meta/info.json` 还给了头部 stereo 的内参、畸变、R 和 T（[S11]）。
- 评测 API（[S13]）：观测是 4 路 RGB、左右臂各 7 维、EE 位姿、夹爪开度、下肢、单字符串语言；动作空间 `joint` / `ee` 二选一；`obs_delta_indices` 决定传哪些键和堆几帧；`image_resize`、`action_chunk_size` 自定；没有力/力矩观测。
- Dex1-1 是**两指平行夹爪**：90mm 行程、5–120N 可调夹持力、0.24s 全行程、0.1mm 指尖分辨率、80mm 爪长（[S14]）。这使解析式对跖抓取采样 + 几何评分重新变得可行；但 API 只给夹爪开度，不给力，所以“力控”只能做闭合力/开度反射，不能做真正的力反馈。
- 头部 stereo 是已校正的，可以直接做双目深度/点云；腕部相机做局部视觉伺服。**这意味着我们可以在推理时构造度量 3D 抓取候选，而不是只让 VLM 吐一个 2D 坐标。**

### 0.6 论文侧：抓取-放置的耦合已经被证明，但还没人把它做成 UniBot 的“单模型接触接口”

- **Pick2Place**（ICRA 2023）：抓取选择必须考虑下游放置；用物体中心的放置 affordance 建立 pick-place 一一映射，真机 placement-aware grasping 超过 **89%**，并能泛化到新物体/新场景（[S19]）。
- **Grasp-Dependent Feasibility**（ACRA 2025）：给定候选抓取，用路径 IK 可行性和运输碰撞标签来排序 grasp-place 候选；便宜、无物理的监督就能让规划器更早找到可行路径（[S20]）。
- **GTP-FA**（2026）：把“抓取失败”和“下游规划失败”显式归因，再做诊断驱动优化；说明抓取与规划紧耦合时，不归因就会把错误归错模块（[S25]）。
- **CoDex**（ICRA 2026）：VLM 从任务/场景推断语义约束，指导解析式约束优化生成功能性抓取候选，再用 RL 精化；零演示、跨新物体（[S21]）。
- **GLOVER / OVAL-Grasp / VLAff**：VLM/LLM 做开放词汇 affordance 与部件定位，GLOVER 部件识别 86.0%、抓取 76.3%（[S22]）；OVAL-Grasp 部件分割 95%、正确抓取 78.3%、遮挡下 80%（[S23]）；VLAff 把视觉/抓取/轨迹 affordance 统一成一个模型（[S24]）。
- **ActionGround**（2026）：不训练、不碰权重，给冻结 VLA 外套一个相位状态机 + 规则修正，LIBERO-Spatial 最高 +6pp，延迟 <1ms（[S27]）。这说明“接触相位 + 规则守卫”本身就能赚钱。
- **FR-VLA / Opt2VLA**（2026）：接触丰富任务里，显式力推理/力命令很有效（[S28][S29]）。但 UniBot API 没有力观测，这条线只能作为“用开度/视觉代理力”的弱化版。

一句话：**VLM 知道“抓哪里”，几何规划知道“怎么抓得稳”，放置可行性知道“抓了之后放不放得下”，但三者目前是分开的；UniBot 恰好要求一个模型把三者接起来。**

## 1. 三个灵感词，各自钉到赛事事实上

### 1.1 视觉语言模型：不是运行时第二个模型，而是离线“接触规范教师”

VLM 在 UniBot 里最诱人的用法是“看图说话，直接出抓取点”。但这条路的证据是分裂的：

- 好的一面：开放词汇部件定位已经很强（OVAL 95% 部件分割、78.3% 正确抓取；GLOVER 86%/76.3%），而且能处理未见物体和遮挡（[S22][S23]）。
- 坏的一面：VLM 的**度量精度**不够，直接吐 3D 坐标/6D 位姿容易在最后几厘米崩；Spa-Bench 也表明 OOD 空间 grounding 是主要瓶颈（上一轮已引）。VLM 更适合回答“抓把手还是抓杯身”“插头哪一端朝前”“拉链头在哪”，而不是“EE 的 z 轴应该是 0.732”。

更关键的是合规：比赛明确“单模型、不得混合多个模型”（[S2][S3]）。如果运行时同时跑一个 VLM 做规划、一个 VLA 做动作，审计上很危险。所以我的判断是：

> **VLM 只做离线教师/标注器**：用它在 33k 演示上生成“接触规范”（抓取部位、接近方向、放置目标、双手角色、成功谓词），把这些标签蒸馏进**唯一 checkpoint** 的辅助头；运行时不再调用第二个 VLM。这样既拿到 VLM 的语义先验，又守住单模型边界。

这不是“不用 VLM”，而是把 VLM 用在它最擅长、且不违反规则的位置。

### 1.2 抓取规划：不是“抓稳”，而是“抓了之后放得下”

传统抓取规划的目标是力闭合/稳定性。UniBot 的任务不是“把物体抓起来就结束”，而是“抓起来之后要挂、要插、要叠、要拉、要倒”。所以真正的目标函数应该是：

```text
抓取分数 = 稳定性 × 运动学可达 × 无碰撞 × 任务部位正确 × 下游放置可行 × 失败可恢复
```

这就是 Pick2Place 和 grasp-dependent feasibility 的核心（[S19][S20]）。具体到 UniBot：

- **T01 HangCup**：必须抓杯柄，抓杯身即使稳定也挂不上；抓杯柄后还要保证杯口朝向能套进杯架。
- **T10 PlugCharger**：抓插头本体、让插脚朝前；抓线会软、抓插排会挡插座。
- **T19 ZipUp**：要抓拉链头而不是布面；拉合过程中两只手要分工（一手固定包、一手拉拉链）。
- **T27 StackBowls**：抓碗沿/碗身要留出底部支撑面；从正上方放，夹爪不能先碰到下面的碗。
- **T14 PourOutMedicine**：一手固定瓶身、一手拧盖；抓瓶身的位置不能挡住倒药口。

这些都不是“抓取稳定性”能单独解释的，而是**抓取-放置联合约束**。首步 16 个抓取任务（560 分）是直接受益者；其余任务里的“抓了再放”步骤也间接受益。

### 1.3 场景驱动创新：把 5 轴 × 2 次当成“需求文档”，不是“数据 augmentation”

官方评测结构是 5 类泛化 × 每类 2 次（[S2][S3]）。这给了我们一个非常具体的研发单位：**场景卡（scenario card）**。每张卡写清楚：

- 哪个任务、哪个轴、第几次；
- 初始状态怎么变（物体/目标/背景/干扰物/未见物）；
- 人为干扰在哪个步骤触发、做什么（官方 `human_1_note` / `human_4_note` 已经给了逐任务剧本，[S8]）；
- 成功谓词是什么；
- 期望的恢复动作是什么。

这样做的三个好处：

1. **训练**：可以做“配对场景”——同一初始状态，只改一个轴，训练模型对位置等变、对背景/干扰物不变、对人为干扰可恢复。
2. **评测**：本地就能复现 5×2 的结构，报告“每轴成功率/最差轴”，而不是只看一个平均数。
3. **归因**：某个轴掉点，能直接定位是感知、抓取、放置还是恢复的问题；这比“再采 10 万条数据”精确得多。

场景驱动不是“造更多数据”，而是**用评测结构反推方法结构**。

## 2. 本轮主判断：从“只攻出口”改为“抓取-放置联合编译”

### 2.1 一个新失败模型：任务不是轨迹，是一串接触转移

把 32 个任务重新看一遍，会发现它们更像**接触转移图（Contact Transition Graph, CTG）**：

```text
状态(物体/关系) --抓取/放置/插入/闭合/倾倒--> 状态(物体/关系) --...--> 成功
```

官方 `score_steps` 就是这张图的边和权重；`generalization` 备注就是人为干扰的“反向边”（先叠后撤、拉上再拉开、拧开再拧回）。上一轮的 SSG 是“线性步骤图”，本轮把它升级成“带接触几何的图”：每条边不只有文字和权重，还有抓取部位、接近方向、放置位姿、双手角色、成功谓词和容差。

于是失败可以分成五类，而不是笼统的“模型不行”：

| 失败层 | 典型现象 | 该谁负责 |
|---|---|---|
| 感知/接地 | 抓错物体、抓错部位、目标槽位错 | VLM/分割/位姿 |
| 抓取 | 夹空、滑落、抓了但拿不起来 | 抓取规划/夹爪反射 |
| 运输 | 碰撞、掉落、路径不可达 | 运动规划/接触守卫 |
| 放置/插入 | 没对准、没插到底、释放过早、叠歪 | 放置规划/伺服/守卫 |
| 干扰/恢复 | 人把物体移走/撤销后不知道怎么办 | 事件检测/重规划 |

**这五层里，抓取和放置是两端；中间三层是守卫。** 上一轮只盯放置，等于只修了出口；本轮把入口和出口一起修。

### 2.2 为什么这比“再换一个更大的 VLA”更值得做

- 榜单前三已经证明：ARM、VLA、WAM 三种范式在 320 次试次下只差 1.8pp，落在噪声里。**继续换底座，边际收益大概率小于接触层的一个确定性改进。**
- MolmoAct2 自己承认开环执行、不中途重推理；DreamZero 是 14B/7Hz；WALL-OSS 是跨形态预训练——三者都不是为 G1 + Dex1 的“小物件、窄间隙、双手协作”专门优化的。**它们缺的不是语义，而是接触层的接口。**
- 首步 + 终步合计 75.3% 的步骤分，且都是成功闸门；抓取-放置联合做对，直接覆盖两端。
- 这套方法可以在**不重训大模型**的情况下先落地（解析规划器 + 接触守卫），再逐步蒸馏进单模型；风险可控。

### 2.3 预期收益的粗算术

假设只在 16 个“首步抓取”任务上把首步成功率提高 10pp，其他不变：

```text
总成功率增益 ≈ (16 / 32) × 10pp = +5.0pp
```

假设在全部任务上把终局成功率提高 10pp，且到达终局的比例 q≈0.6：

```text
总成功率增益 ≈ 0.6 × 10pp = +6.0pp
```

两者有重叠，不能直接相加；但合起来的目标可以定在 **+4–6pp**（从 29.7% 到 34–36%），保守目标 +3pp。这个量级在 320 次试次下仍然会被噪声淹没（SE≈2.56pp），所以必须用**配对场景 + 多任务聚合 + 调试槽**来验证，不能只看一次总分。

## 1. 事实核对（本轮新增/复核）

### 1.1 赛制：10 次/任务、5 轴 × 2、180s、成功率优先

官方参赛手册（中文 [S2]、英文 [S3]）明确：

- 每个任务独立跑 **10 次**；5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰）**每类各 2 次**；
- 单次真机执行最大 **180 秒**，超时失败，并按执行情况给步骤分；
- 实时榜单**按 32 个任务的总平均成功率排序**；成功率相同看总平均步骤分；再相同看提交日期；
- 只有“单模型 + 全 32 任务”进榜；单任务测试通道不计分，但可用于调试。

这修正了上一轮的一个隐含偏差：PILOT 用“终局步骤占 39.8% 步骤分”论证放置优先，但**步骤分只是平分决胜**。真正该看的是“哪些步骤是成功闸门”。结论不是“放置不重要”，而是“首步和终步都是闸门，不能只攻出口”。

### 1.2 榜单：前三名在统计上不可区分，且当前数据仍是占位

榜单页显示 8 条记录：MolmoAct2/DexHacker **29.7% / 39.0**；WALL-OSS-0.5 **28.5% / 38.9**；DreamZero **27.9% / 37.9**；其后 Spirit-v1.5 25.9、DM0 23.5、PI-0.5 22.8、GigaBrain-0 22.6、GR00T N1.5 20.5（[S4][S5]）。但：

- `leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`（[S5]）；
- `details.html` 全部任务视频仍是“测试视频占位，后续可替换为真实视频文件”（[S7]）；
- `runs.html` 是 256/256 条记录的占位页（[S6]）；
- 页面仍有“即将发布 / Coming Soon”（[S4]）。

**结论：8 条记录只能当官方基线/占位先验，不能当真实赛果，也不能用来判断模型强弱。** 即便假设数字是真的，前三名 1.8pp 的差距不到 1 个总体标准误（2.56pp）；在 320 次试次下，ARM、VLA、WAM 三种范式的榜首差异落在噪声里。**换底座的边际收益大概率小于接触层的一个确定性改进。**

## 2. 问题形式化：接触转移图与两道闸门

### 2.1 接触转移图（CTG）

对任务 \(t\)，官方步骤 \(s_1,\dots,s_k\) 给出文字与权重 \(w_i\)。我们构造有向图：

\[
G_t = (V_t, E_t),\quad
e_i = (pre_i, a_i, post_i, w_i, c_i)
\]

- \(pre_i, post_i\)：物体/容器/夹爪的关系谓词（如 `on(bowl2,bowl1)`、`inserted(plug,socket)`、`zipped(pouch)`）；
- \(a_i\)：接触动作（grasp/place/insert/close/zip/pour/...）；
- \(w_i\)：官方步骤分；
- \(c_i\)：接触规范（抓取部位、接近方向、放置位姿、双手角色、容差、失败恢复）。

另有恢复边 \(e_i^{rec}\)：当人为干扰把 \(post_i\) 撤销（先叠后撤、拉上再拉开、拧开再拧回），从当前状态回到 \(pre_i\) 或中间状态。官方 `human_1_note`/`human_4_note` 就是这些恢复边的剧本（[S8]）。

### 2.2 成功与闸门

任务成功要求所有步骤完成：

\[
\text{success}_t = \prod_{i=1}^{k} \mathbf{1}[\text{post}_i \text{ 达成}]
\]

首步和终步都是乘积中的因子；任一项为 0，成功为 0。步骤分是部分分：

\[
\text{stepscore}_t = \sum_i w_i \cdot \mathbf{1}[\text{post}_i \text{ 达成}]
\]

排名先看 \(\frac{1}{32}\sum_t \text{success}_t\)，再看的步骤分。**因此优化目标应以“成功”为主，步骤分用于诊断和平分。**

### 2.3 联合抓取-放置目标

对每个接触边 \(e_i\)，候选抓取 \(g\) 与放置 \(p\) 不是串联独立选择，而是联合选择：

\[
(g^*,p^*) = \arg\max_{g\in\mathcal{G}, p\in\mathcal{P}(g)} S(g,p;e_i)
\]

\[
S = \lambda_1 S_{stab} + \lambda_2 S_{kin} + \lambda_3 S_{col} + \lambda_4 S_{task} + \lambda_5 S_{place} + \lambda_6 S_{rec}
\]

| 项 | 含义 | 计算 |
|---|---|---|
| \(S_{stab}\) | 对跖/力闭合稳定性 | 摩擦锥、质心、Dex1 5–120N、90mm 行程 |
| \(S_{kin}\) | 7 维臂 IK 可达/关节限位 | 解析/数值 IK |
| \(S_{col}\) | 接近/运输/释放无碰撞 | 扫掠体 + URDF + 场景点云 |
| \(S_{task}\) | 抓取部位是否符合任务 | VLM 教师标签 + 单模型 heatmap |
| \(S_{place}\) | 该抓取下的放置可行性 | 目标位姿、支撑面、插入轴、夹爪间隙、释放高度 |
| \(S_{rec}\) | 失败后可重抓/可恢复 | 抓取外露度、重抓路径、候选多样性 |

硬约束先过滤：\(S_{stab}>\tau_s\)、\(S_{kin}>\tau_k\)、\(S_{col}=0\)；再在可行集内排序。这样避免“稳定但放不下”的抓取被选中。

### 2.4 任务原型

| 原型 | 任务 | 关键约束 |
|---|---|---|
| 纯两步抓放 | T01、T02、T03、T05、T08、T14、T19、T23、T24、T30、T32（1100 分） | 抓取部位 + 放置/闭合/抽取的配对 |
| 多物体抓放 | T04、T06、T13、T15、T20、T21、T25、T27 | 每次抓放都要保持顺序/位置 |
| 功能抓取 | T01 杯柄、T05 网口+网线、T10 插排+插头、T12 锁+钥匙、T19 拉链、T26 网口+网线、T31 拉链、T32 注射器 | 抓错部位直接失败 |
| 双手协作 | T14 拧盖/倒药、T16 叠毛巾、T19 拉拉链、T23 球拍套、T30 拔钉、T31 笔袋、T32 抽水/注水 | 角色分配 + 臂间避碰 |

### 3.3 CGH：单模型接触头

在 WLA/VLA 主干上增加轻量头（同一 checkpoint，不是第二个模型）：

| 头 | 输出 | 监督 |
|---|---|---|
| grasp-part | 物体掩码上的部件热图（handle/rim/body/tab/plug/cap...） | VLM 教师 + 演示抓取点投影 |
| approach | 单位向量（base 系） | 演示抓取前 EE z 轴/接近方向 |
| place pose | 目标系 6D 位姿 + 容差 | 演示释放位姿相对容器/目标系 |
| edge state | 当前 CTG 边/步骤完成概率 | 演示相位切分 + 事件 |
| failure mode | grasp/place/perception/disturbance/execution | 失败回放/合成扰动 + 规则标签 |
| roles | 左右手角色分布（grasp/stabilize/actuate/idle） | 演示双臂使用 + VLM 教师 |

损失：

\[
L = L_{action} + \lambda_1 L_{part} + \lambda_2 L_{approach} + \lambda_3 L_{place} + \lambda_4 L_{edge} + \lambda_5 L_{fail} + \lambda_6 L_{role}
\]

- \(L_{part}\)：focal/BCE（部件热图）；
- \(L_{approach}\)：余弦相似度；
- \(L_{place}\)：位置 L2 + 四元数/旋转测地距离；
- \(L_{edge}\)：BCE；
- \(L_{fail}\)：交叉熵；
- \(L_{role}\)：左右手角色 BCE/CE。

**训练时必须混合“接触头预测”和“动作生成”**，否则头学好了但动作不用；推理时把接触头输出渲染成锚点/6D 目标，作为 VLA 的额外输入。

### 3.4 JGP：联合抓取-放置规划

#### 3.4.1 候选生成

1. **点云**：头部 stereo 校正图 → 双目匹配/深度 → 反投影；桌面平面 RANSAC 去除；物体掩码来自开放词汇分割（或 CGH heatmap）。
2. **抓取采样**：对每个物体点云采样对跖点对；抓取宽度 \(w<85\)mm（90mm 行程留 5mm 余量）；爪长 80mm；接近方向沿局部法向/半球采样；过滤桌面/相邻物体碰撞。
3. **放置候选**：由 CTG 目标系 + CGH place pose + 场景点云生成；每个抓取 \(g\) 生成 3–5 个放置候选 \(p\)（目标位姿、释放高度、插入轴）。
4. **剪枝**：IK 不可达、关节限位、臂-桌/臂-物体碰撞、夹爪-目标间隙不足的候选直接丢弃；保留 top 20 抓取 × top 5 放置。

#### 3.4.2 评分与选择

```text
for g in Grasps(object, edge):
    if not stable(g): continue
    if not reachable(g): continue
    for p in Placements(g, edge):
        if collision(g, p): continue
        s = w1*stab(g) + w2*ik(g) + w3*task(g, edge)
          + w4*place(p, g, edge) + w5*recover(g) + w6*biarm(g, p, roles)
        keep top-k (g, p, roles)
return argmax s
```

- `place(p,g,edge)`：目标位姿可达、支撑多边形、插入轴对齐、夹爪释放间隙、释放后稳定性、物体-容器碰撞。
- `recover(g)`：抓取外露度、重抓路径、候选多样性。
- `biarm(g,p,roles)`：双臂角色可行、臂-臂碰撞、协调时序。

#### 3.4.3 为什么不是“先抓再找地方放”

因为很多抓取在抓的瞬间是稳定的，但在放置时夹爪会卡住/挡住/放不平。Pick2Place 的核心就是建立 pick-place 的一一映射（[S19]）；grasp-dependent feasibility 进一步证明抓取选择会影响运输 IK 和碰撞（[S20]）。**JGP 把“放置可行性”提前到抓取选择阶段，避免“抓起来才发现放不下”。**

### 3.5 CG：接触守卫

```python
def execute_edge(edge, obs, policy, planner, budget=2):
    pair = planner.select(edge, obs)
    for attempt in range(budget + 1):
        # 1) grasp reflex
        approach(pair.grasp, obs)
        close_slowly_until_width_stops()
        extra_close(1.0)                 # 1mm 级过闭合，建立接触
        lift(0.02)
        if not object_moves_with_gripper(obs):   # 腕部视觉/开度
            pair = planner.next_grasp(edge, obs); continue

        # 2) transport + place
        for chunk in policy.stream(obs, edge, pair):
            send(chunk)
            if edge_predicate_met(edge, obs):
                break
            if collision_risk(obs) or object_slipped(obs):
                break

        # 3) insert / release / settle
        if edge.type in ("insert", "plug", "zip", "close"):
            align_axis(pair); slow_insert(); if not seated(edge, obs):
                wiggle(); retry_insert()
        else:
            lower_until_support(obs); open_slowly(); wait(0.4)
            if stable(edge, obs, window=0.4):
                return True

        # 4) failure attribution + recovery
        mode = diagnose(edge, obs)       # grasp/place/perception/disturbance/execution
        pair = planner.revise(edge, obs, mode)
    return False
```

**失败归因规则（先规则后学习）**：

| 观察 | 归因 | 恢复 |
|---|---|---|
| 夹爪闭合但物体未抬起 | grasp | 换下一个抓取候选 |
| 抬起后滑落/腕部视觉相对位移 | grasp/transport | 加大闭合/换抓取/降速 |
| 目标前碰撞/过冲 | place | 重选放置位姿/减速 |
| 插入不到位/卡住 | place/insertion | 对准轴/微摆/二次插入 |
| 释放后物体移动/倒下 | place/settle | 重新抓取/推正 |
| 物体被外力移走/撤销 | disturbance | 重新定位，回到当前边 |
| 抓错物体/部位 | perception | 重新分割/重选部件 |

这套规则可以直接从 GTP-FA 的失败归因思想借鉴（[S25]），但用确定性规则实现，避免运行时第二个模型。

### 3.6 BCR：双手角色

对每个接触边，定义角色集合：

\[
r_i = (r_i^{L}, r_i^{R}) \in \{\text{grasp, stabilize, actuate, support, idle}\}^2
\]

- T10：左手稳定插排，右手抓插头插入；
- T14：左手固定瓶身，右手拧盖/倒药；
- T19：左手固定包体，右手拉拉链（或双手交替）；

#### 3.7.2 配对场景

对每个任务，同一初始状态生成一对场景，只改一个轴：

```text
pair(task, axis) = (seed_scene, seed_scene + one_axis_perturbation)
```

- 位置：物体/目标平移/旋转；
- 干扰物：插入 1–3 个无关物体；
- 背景：桌布颜色/纹理替换；
- 未见物品：同功能类别替换（不同颜色/形状/材质）；
- 人为干扰：在指定边后执行官方剧本/通用扰动。

训练时配对样本共享任务/接触规范，鼓励：
- 位置轴：对物体/目标相对位姿**等变**；
- 背景/干扰物轴：对纹理/ clutter **不变**；
- 未见物品：对部件/affordance **不变**；
- 人为干扰：对事件**可恢复**。

#### 3.7.3 逐轴训练目标

不要只做平均 ERM。用任务平衡采样 + 轴组重加权：

\[
L = (1-\beta) L_{ERM} + \beta \sum_{a\in A} q_a L_a
\]

其中 \(A\) 是 5 个轴，\(q_a\) 按当前轴成功率/损失自适应（类似组 DRO，[S30]），\(\beta\) 从 0.1 渐增到 0.3。目标不是牺牲平均去救最差轴，而是**在平均不降的前提下抬最差轴**；如果平均降超过 1pp，回退 \(\beta\)。

### 3.8 接口工程

| 项 | 选择 | 理由 |
|---|---|---|
| 动作空间 | `ee` 优先 | JGP 输出 6D 位姿；底层 IK 由控制器处理；与演示 EE 位姿一致 |
| 观测 | 4 路 RGB + 双臂 7 维 + EE + 夹爪 + 下肢 | 与 API 目录一致；不用数据集里的 torso/d435/waist 额外键（推理不可用） |
| 时序堆叠 | 2–4 帧（VLA）；JGP 用当前帧 | 兼顾速度/动作平滑 |
| 图像缩放 | VLA 240×320；JGP 关键帧 480×640 | 控制延迟；保留度量精度 |
| chunk | 8–16 | 与 30Hz 控制、接触守卫的响应频率折中 |
| 深度 | 头部 stereo 双目匹配 | API 无深度；stereo 已校正 |
| 延迟目标 | VLA p99 <150ms；JGP 仅在接触边 <150ms；总 <300ms | 180s 预算充足，但多端口并发要留余量 |
| 部署 | 共享推理后端 + N 端口状态隔离 | README 允许；每端口 reset 独立（[S13]） |
| 安全 | 力限/速度限/碰撞检查/180s 守卫 | Dex1 5–120N；避免损坏 |

## 5. 训练配方

### 5.1 底座

- 主选：**WLA-1.0-Base**（Unitree，Apache-2.0，6B，24GB 可微调，[S31]）——与 G1 同源，部署/许可最稳。
- 备选：**WALL-OSS-0.5**（4B，跨 20+ 形态，[S16][S17]）——如果双臂/多形态先验明显更好，用离线 held-out 决定，不看占位榜。
- 不建议：从零训练；14B WAM 全量微调（算力/延迟不划算）；每任务 LoRA（违反单模型精神，且 32 个模型切换）。

### 5.2 课程

| 阶段 | 数据 | 目标 | 退出条件 |
|---|---|---|---|
| 0 | 真实 100% | 复现基线 | held-out 不降 |
| 1 | +CTG/TCS 标签 | edge state/谓词稳 | 谓词 F1 +5 |
| 2 | +CGH 抓取部位/接近 | 部件热图/方向准 | 部件准确率 ≥80% |
| 3 | +place pose/roles | 放置位姿/双手角色 | 放置误差 <1cm |
| 4 | +JGP 推理（不训练） | 联合选择优于贪心 | replay 成功率 +5pp |
| 5 | +CG（不训练） | 抓取反射/释放/插入 | 首步/终步 +5pp |
| 6 | +SCM 配对/组 DRO | 逐轴鲁棒 | 最差轴 +3pp，平均不降 |
| 7 | 蒸馏/量化 | 延迟达标 | p99 <150ms |

### 5.3 损失

\[
L = L_{action} + 0.2 L_{edge} + 0.1 L_{part} + 0.05 L_{approach} + 0.1 L_{place} + 0.05 L_{fail} + 0.05 L_{role} + \beta L_{axis}
\]

权重是起点，按验证集调；接触头损失不能压过动作损失（否则动作退化）。

### 5.4 超参

- LoRA rank 64 / alpha 128；action expert 全量或 LoRA；
- AdamW，lr 1e-4（LoRA）/2e-5（全量），cosine，warmup 3%；
- global batch 64–128；bf16；chunk 8–16；horizon 1–2s；
- 早停看真实 held-out + 逐轴诊断，不看占位榜/仿真成功率；
- 随机种子 ≥3；报告均值/方差。

### 6.4 评测协议

1. **离线（每天）**：held-out 场景/物体上的部件准确率、抓取成功率、放置误差、谓词 F1。验收：部件 ≥80%，释放位姿在容差内 ≥80%。
2. **本地（每周）**：8 任务子集 × 10 场景（5 轴 × 2），配对种子；报告首步/终步/逐轴。只做相对比较，不做模型选择唯一依据。
3. **平台（版本门）**：不计分单任务调试槽；首选 T01（功能抓取）、T27（叠放）、T10（插入）、T19（拉链/双手）。判定：首步/终步 ≥+10pp 且无回归才进计分跑。
4. **计分跑**：W7 中期、W8 终期；若只允许 1 次，W8 唯一一次。

### 6.5 统计

- 320 次计分试次，p≈0.3，SE≈2.56pp；
- 单任务 10 次，SE≈14.5pp；不要用单任务差异下结论；
- 配对场景/配对种子做差；bootstrap 95% CI；多任务聚合；
- 目标 +3pp 是务实目标，+5pp 是乐观目标；<3pp 的单次差异不立项。

| 决策 | Go | No-Go |

## 9. 创新点清单（持续迭代）

> 状态：押注=本轮主线；保留=沿用；升级=旧点改造；降级=保留但非主线；砍=不做。

### I1 CTG 接触转移图（升级 SSG｜押注）

- **动机**：官方步骤是接触转移，不只是文字步骤；首步 35.5% + 终步 39.8% 都是闸门；需要把抓取/放置/角色/谓词写进图。
- **与现有方案差异**：SSG 是线性步骤图；CTG 增加接触几何、恢复边、双手角色、容差；可直接映射到官方 `score_steps`。
- **可行性**：32 个 `info.json` 已公开；schema 可手写 + VLM 教师补全；无额外数据。
- **资源**：1–2 人周；CPU；32 任务。
- **步骤**：解析 → schema → 100 条/任务标注 → QA → 接入状态机。
- **风险**：步骤文字歧义；VLM 标签噪声；用人工抽检/演示统计兜底。

### I2 CGH 单模型接触头（新增｜押注）

- **动机**：运行时只能有一个学习模型；需要把 VLM 的部件/放置知识蒸馏进策略，而不是再跑一个 VLM。
- **与现有方案差异**：不是外挂 VLM，而是 WLA/VLA 主干上的辅助头；输出 grasp-part/approach/place/edge/failure/roles；同一 checkpoint。
- **可行性**：WLA 有 VLM 主干；辅助头轻量；33k 演示 + 离线标签足够。
- **资源**：8×H100 2–3 周；9,600 条标签；1 人。
- **步骤**：标签 → 头 → 损失 → 离线指标 → 接入动作。
- **风险**：头干扰动作；数据不平衡；单模型审计；用 loss 权重/早停/模型卡缓解。

### I3 JGP 联合抓取-放置规划（新增｜押注）

- **动机**：抓取选择决定放置可行性；首步 16 个抓取任务；Pick2Place/grasp-dependent feasibility 已证明。
- **与现有方案差异**：不是“先抓再找地方放”，而是对 (grasp, place, roles) 联合评分；Dex1 几何；确定性代码。
- **可行性**：双目点云 + 解析对跖采样 + IK/碰撞；Dex1 90mm/5–120N；数据有 EE 位姿。
- **资源**：CPU/GPU；1–2 人周；URDF/点云库。
- **步骤**：深度 → 掩码 → 候选 → 评分 → top 对 → 锚点渲染。
- **风险**：深度噪声/遮挡/透明；延迟；回退 VLA 或腕部视觉。

### I4 CG 接触守卫（升级 SVL｜押注）

- **动机**：榜首模型开环执行；人为干扰/释放/插入失败无法自愈；180s 预算允许 1–2 次重试。
- **与现有方案差异**：从“落点 settle”升级为“相位状态机 + 抓取反射 + 插入/释放 + 失败归因 + 重试”；用开度/腕部视觉代理力。
- **可行性**：确定性代码；ActionGround/GTP-FA/Blind Grasp Reflex 先例；无需新数据。
- **资源**：1–2 人周；阈值从演示统计。
- **步骤**：相位检测 → 抓取反射 → 释放/插入校验 → 归因 → 恢复。
- **风险**：误判/耗时；长任务限 1 次；双阈值。

### I5 SCM 场景编译器（升级 NRB｜押注）

- **动机**：官方 5 轴 × 2 次；平均成功率排名；官方 human 备注逐任务公开；随机增强不够。
- **与现有方案差异**：场景卡 + 配对场景 + 组 DRO；官方备注作为人为干扰剧本；逐轴诊断。
- **可行性**：2.5D 编辑 + 刚体合成；32 任务；官方备注。
- **资源**：2–3 人；2.5D 管线；8×H100 3–4 天。
- **步骤**：场景卡 → 配对数据 → 训练 → 逐轴评测。
- **风险**：过拟合备注/合成；平均掉点；β 回退。

### I6 BCR 双手角色（新增｜高优先）

- **动机**：32 任务含双手协作；榜单难点多为双手/接触丰富；G1 双臂数据可用。
- **与现有方案差异**：显式角色分配 + 联合抓取规划；不是让模型自己学“用哪只手”。
- **可行性**：演示双臂使用可标；角色头轻量；JGP 检查臂间碰撞。
- **资源**：1–2 人周；标签。
- **步骤**：角色标签 → 头 → JGP → 双手任务评测。
- **风险**：臂间碰撞；单臂偏置；数据不平衡。

### I7 VLM 离线教师（新增｜使能）

- **动机**：VLM 懂部件/affordance，但度量精度不足，且运行时不能多模型。
- **与现有方案差异**：只在离线标注；3 提示自一致性；蒸馏到 CGH；不参与推理。
- **可行性**：开源 VLM；9,600 条演示；提示工程。
- **资源**：2–3 天 GPU；1 人。
- **步骤**：提示 → 标签 → QA → 蒸馏。
- **风险**：标签噪声/许可；低置信度丢弃；模型卡披露。

### I8 DebugLoop + 逐轴评测（保留｜工程策略）

- **动机**：真机反馈比自建孪生可信；单任务调试槽不计分。
- **与现有方案差异**：把调试槽当发布门，不当调参器；每次大版本 1 槽；固定任务/判定。
- **可行性**：官方 profile 页已提供；次数未知。
- **资源**：3–4 槽；1 人。
- **步骤**：选 T01/T27/T10/T19 → 判定标准 → 记录 → Go/No-Go。
- **风险**：稀缺/方差；用配对/多次聚合。

## 11. 开放问题

1. 榜单 8 条记录何时替换为真实赛果？当前 `gen_leaderboard.py`/视频占位是否只是开发占位？
2. 单任务调试通道是否也跑 10 次/5 轴？能否指定场景？可用次数/成本？
3. “单模型”边界：确定性 JGP/CG 是否允许？离线 VLM 教师产出的标签是否需要在模型卡披露？
4. 评测 API 是否真的完全没有力/力矩/电流？能否从关节电流估计接触力？（README 只列开度）
5. N 台评测机器人的准确数量；每端口延迟/并发上限；是否允许共享推理后端。
6. 外部数据（自采/实验室）是否允许？预训练权重（含论文方法）是否允许？
7. 评测指令是否从 5 条英文复述采样？是否可能出现中文/未见复述？
8. 步骤分聚合公式（按 episode 部分分平均？取最好？）与成功判定细节。
9. 腕部相机是否有可用的外参到 EE？`camera_params` 里腕部只有内参/IR 外参，需用 URDF 标定。
10. 真实榜单发布后，重跑“首步/终步闸门”假设；若首步失败占比 <20%，则本轮优先级需调整。
