# 第 8 轮（新循环 R2）· AnchorFlow：把流匹配的起点从噪声搬到演示锚点，把边缘算力花在闸门上

> 日期：2026-10-24（UTC）。对象：宇树 UniBot 世界挑战赛（G1 + Dex1，32 个桌面任务，通才单模型，自部署 + 官方远程真机评测）。
> 本轮灵感词：**流匹配策略**、**论文发表**、**边缘计算**。
> 承接：状态文件上一轮为第 7 轮「PILOT」；本轮是新循环第 2 轮，编号沿用第 8 轮。
> 结论先行：**最值得押注的是「演示锚定的少步流匹配」（AnchorFlow / DAFB）**——把 WLA 动作专家的源分布从高斯噪声换成「由跨回合演示导出的容器系释放位姿 + 平滑插值动作块」，用带锚点扰动的 flow bridge 训练，用锚点离散度做不确定性门控，再蒸馏成 1 步边缘策略。它同时攻成功率闸门、OOD 位置/背景轴和部署延迟，而且天然是一篇关于「流策略源分布」的可发表论文。

## 0. 本轮先核实：六件事，先纠偏再谈创新

### 0.1 规则：成功率先行，步骤分只做平局裁决

官方手册（中文版 / 英文版）明确：32 个任务各跑 10 次，5 类泛化（位置、干扰物、背景、未见物品、人为干扰）各 2 次；**排名先看 32 任务总平均成功率，成功率相同才看总平均步骤分，仍相同则提交早者靠前**。单次真机最长 180 秒，超时判失败；选手自部署，需暴露 N 个连续端口（8765 起），延迟与返回内容被记录，要求平滑稳定；必须单模型覆盖全部任务，架构不限（VLA / World Model 均可）；有不计分的单任务测试通道。

这直接修正上一轮的两个偏差：

1. 上一轮把「成功率」和「步骤分」并列，甚至用「终局放置约占 60% 步骤分」当预算依据——**不准确**。步骤分只在成功率打平时才起作用，不能拿它当主目标。
2. 上一轮把「放置精度」当成分数银行——**应降级为成功率闸门之一**。放置失败会直接丢掉该次运行的成功率，而不是只扣步骤分；反过来，放置再漂亮，成功率不上去也没有排名收益。

所以本轮所有候选创新点都要先过一道题：**它是否提高「整条任务跑完」的成功率？** 如果只是让轨迹更漂亮、步骤分更高，先降级。

来源：官方中文手册 <https://scnhkkqlu12w.feishu.cn/docx/Uz7OdFBcDoqP1dxgH62cHW1CnMh>；英文手册 <https://scnhkkqlu12w.feishu.cn/docx/ZNHIdaGx0oPOlBxNVxkcswqqnnh>；挑战赛页 <https://unibot.unitree.com/challenges.html>；检索日期 2026-10-24。

### 0.2 榜单与运行记录仍是占位，不能当真实排名证据

`leaderboard.html` 与首页目前展示 8 个模型（MolmoAct2、WALL-OSS-0.5、DreamZero、Spirit-v1.5、DM0、PI-0.5、GigaBrain-0、GR00T N1.5），第一名约 **29.7% 成功率 / 39.0 步骤分**；但页面同时标注「即将发布 / Coming Soon」，`runs.html` 是 256/256 条记录，详情页视频写着「测试视频占位」。这说明：**这些数字只能当结构样例，不能当真实排名结论**。另外，页面文案写「按平均成功率与步骤分综合排序」，但官方手册明确成功率先行、步骤分只做平局裁决；以手册为准，避免把页面文案误读成加权总分。

### 0.3 WLA-1.0-Base 本身就是 4 步流匹配，这是我们能改的底座

官方 WLA-1.0-Base 不是「扩散策略」的多步去噪，而是**流匹配 / rectified flow**：

- 6B 参数，Qwen VLM + DiT-L action expert；动作维度 54，动作块长度 30，默认推理 4 步；`noise_beta_alpha=1.5`、`noise_s=0.999` 的 Beta 时间采样。
- 代码里 `noisy_actions = (1 - t) * noise + t * actions`，`velocity = actions - noise`，Euler 积分 `actions + dt * pred_velocity`。
- VLM 冻结，只训 action expert（DiT）和 robot-state projector；默认单张 24GB GPU 可微调；Apache-2.0。

这意味着：**「4 步→1 步」的普通蒸馏不是新东西，SnapFlow / One-Step Flow Policy / Coda 已经做了**。我们要找的不是「再快一点」，而是**流匹配里还没被充分利用的轴：源分布**。WLA 的源是纯高斯；WarmPrior 用上一段动作当源；我们想把源换成**演示锚点**。这是本轮的主线。

来源：模型卡 <https://huggingface.co/unitreerobotics/UnifoLM-WLA-1.0-Base>；配置 <https://huggingface.co/unitreerobotics/UnifoLM-WLA-1.0-Base/raw/main/config.yaml>；动作头 <https://github.com/unitreerobotics/unifolm-wla/blob/main/unifolm_wla/model/modules/action_model/MMDiT_ActionHeader.py>；微调文档 <https://github.com/unitreerobotics/unifolm-wla/blob/main/docs/train_action_expert_en.md>；检索日期 2026-10-24。

### 0.4 提交接口允许 EE 控制、观测裁剪、图像缩放、动作块长度和 N 端口

提交 README（中英）确认：4 路 RGB（head_stereo_left/right、wrist_left/right）、双臂关节或 EE 位姿（base 系）、夹爪、单字符串 language；`obs_delta_indices` 决定传哪些键与堆叠帧数；`image_resize` 自定；`action_chunk_size` 自定；joint/ee 互斥；token 两处校验；`reset()` 每 episode 一次；N 个连续端口，共享后端需做并发与状态隔离；延迟与返回内容被记录。

这给我们三个自由度：

1. **EE 控制**：可以直接在 base 系相对位姿上构造「锚点动作块」，与 WLA 的训练空间一致。
2. **观测裁剪 / 图像缩放**：头部双目 + 双腕的 4 路图可以按需缩放，给 VLM 和几何模块留预算。
3. **动作块长度 / N 端口**：可以做 1 步流 + RTC 式的异步块拼接，把延迟藏在执行期。

来源：<https://github.com/unitreerobotics/unibot_submission>；检索日期 2026-10-24。

## 1. 三个灵感词，各自钉到哪个事实上

### 1.1 流匹配策略：源分布是被忽视的轴

流匹配的采样是解 ODE：从源样本 `a_0` 出发，沿学习到的速度场走到 `a_1`。WLA 取 `a_0 ~ N(0, I)`；WarmPrior 取上一段动作块；SnapFlow/One-Step Flow Policy 把 4 步蒸成 1 步；Coda 用端点校正替代多步积分。它们都在改**速度场/步数**，很少有人系统改**源分布**。而源分布决定了三件事：

- **传输距离**：源越接近目标动作，1 步 Euler 的截断误差越小。
- **条件信息**：源本身可以携带「目标在哪」的几何先验，模型不必从纯噪声里重新生成。
- **不确定性**：源的离散度可以直接当置信度，决定要不要多步、要不要引导、要不要回退。

我们的源不是「上一段动作」（WarmPrior），而是**同一任务、同一步骤、跨回合的演示释放位姿**。它回答的是「这一步应该把夹爪送到哪里」，而不是「上一步在哪」。这是更接近任务语义的源。

### 1.2 论文发表：需要一个可被证伪的普遍主张

如果只是「我们调了一个比赛模型」，很难发表。可发表的骨架是：

> **对于少步流策略，源分布的选择（高斯 vs. 历史动作 vs. 演示锚点）系统性地影响 1–2 步采样的成功率、OOD 鲁棒性和量化稳定性；演示锚点 + 锚点扰动训练 + 离散度门控是其中最优的工程折中。**

这个主张可以在 WLA/UniBot 上验证，也可以在 π0.5/RoboTwin 等开源栈上复现；消融清晰（源类型、锚点噪声、NFE、量化位宽），而且有真实人形机器人结果。时间窗：ICRA 2027 已截止（2026-09-16）；RSS 2027 摘要 2026-12-04、终稿 2027-04-16；CoRL 2027 约 2027-05。现实路线是 **arXiv 预印本（2027-01）+ RSS 2027 扩展摘要 + CoRL 2027 全文**，或者直接冲 CoRL 2027。

### 1.3 边缘计算：6B 模型 + 4 步流 + N 端口，算力要花在闸门上

边缘约束不是「跑得动就行」，而是：

- 6B VLM 的前缀计算是固定成本；动作头 4 步是可变成本。
- N 个端口共享后端，延迟和返回内容被记录；不能靠「多开进程」掩盖。
- 180 秒/次，32 任务 × 10 次，任何一次超时都直接失败。

所以边缘优化的正确姿势不是「无脑量化到 4bit」，而是**把算力从「每一步都多步去噪」转到「只在不确定的闸门上多花一步」**：

- 接近段：1 步锚点流，快。
- 放置/插入段：2–4 步 + 几何引导，稳。
- 不确定时：多一步或回退到高斯源；确定时：1 步直接执行。
- 系统层：前缀缓存、连续批处理、RTC 式块拼接、W8A8/W4A16、按端口隔离状态。

锚点源让「1 步」在放置段也可用，这是它和边缘计算的连接点。

## 2. 主判断：成功率闸门在最后一步，而流匹配的源可以提前把终点放对

把 32 个任务按步骤拆开，真正的「全有全无」闸门通常只有几个：

1. **抓取闸门**：没抓住，后面全错。
2. **搬运闸门**：碰撞、掉落、路径被挡。
3. **放置/插入闸门**：位置、朝向、深度、释放时机，差一点就失败。
4. **恢复闸门**：人为干扰/物体被挪走后，能不能重试。

上一轮把「放置」当成步骤分银行，方向偏了；但「放置是成功率闸门」这个判断仍然成立。问题是怎么在**不增加太多推理成本**的前提下，把放置终点放对。

我的判断：

> **与其让 4 步流从高斯噪声里「重新发现」终点，不如把跨回合演示的释放位姿作为源，让流只学「从锚点到当前观测下的正确动作」的残差。** 这样 1 步就能覆盖大部分放置，锚点的离散度还能当不确定性信号，决定要不要多步/引导/回退。

这就是 AnchorFlow（Demonstration-Anchored Flow Bridge，DAFB）。

它和现有工作的差异：

- **vs. WarmPrior**：WarmPrior 的源是时间上的上一段动作，回答「接着刚才往哪走」；我们的源是任务/步骤条件化的演示锚点，回答「这一步的正确终点在哪」。前者在长程漂移时会继承错误，后者用跨回合统计把漂移拉回。
- **vs. SnapFlow / One-Step Flow Policy**：它们蒸馏的是「从高斯源到动作」的映射；我们蒸馏的是「从锚点源到动作」的残差。锚点源传输距离更短，1 步误差更小，量化更稳。
- **vs. Coda**：Coda 在推理时校正端点；我们直接把端点作为源，校正发生在训练里，推理更便宜。
- **vs. OmniGuide / GAF**：它们是测试时引导/价值筛选，不改变源；我们改变源，引导只是可选的第二层。
- **vs. TraceFlow / PreferenceFlow**：它们用检索/人类干预做测试时适应；我们用检索建锚点库，但生成仍由单模型完成，不复制动作。

预期收益（可证伪）：

- 放置/插入任务的**一次成功率**提升；尤其是位置/背景/未见物品三个 OOD 轴。
- 1 步动作头的**端点误差**下降；2 步接近 4 步基线的成功率。
- 量化到 W8A8/W4A16 后，锚点流的**掉点小于**高斯源（因为残差更小）。
- 端到端延迟：动作头 3–4× 加速；加上前缀缓存后，整体延迟明显下降。

如果这些不成立，至少能得到一篇「源分布对少步流策略的影响」的受控研究，仍然是可发表的负结果/中性结果。

## 3. 失败模型与对策：锚点不是万能，先把失败模式列全

| 失败模式 | 触发条件 | 对策 | 对应组件 |
|---|---|---|---|
| F1 目标 grounding 错 | 透明/反光/未见物体；语言指代歧义 | 锚点头 + 跨回合检索 + 多视角一致性 | AnchorHead / ICR |
| F2 碰撞/路径被挡 | 干扰物、狭窄空间、高容器 | 末端几何能量引导；接近段抬升 | GeoGuide |
| F3 朝向错 | 插头、杯子把手、餐具 | SE(3) 锚点 + 旋转向量 + 腕部视觉校验 | Anchor SE(3) |
| F4 释放过早/过晚 | 放置/倒水/挂杯 | 夹爪时序锚点 + 腕部终点校验 + 重锚定 | GripperAnchor / SVL |
| F5 插入深度不够 | 插孔、堆叠、抽屉 | 插入轴能量 + 深度/接触校验 | GeoGuide / SVL |
| F6 失败后不恢复 | 人为干扰、物体被挪走 | 重锚定 + 重试 + 官方 human note 训练 | NRB / ReAnchor |
| F7 锚点本身错 | 新容器、新位置、估计误差 | 离散度门控 + 高斯回退 + 双源验证 | UGA |
| F8 延迟/超时 | 多步 + 引导 + 重试 | 阶段化 NFE + 预算守卫 + 前缀缓存 | PAC / Edge |

关键点：**锚点错了要有退路**。所以 AnchorFlow 不是「把高斯源删掉」，而是「默认锚点源，低置信时回退高斯源/多步」。这也是论文里「鲁棒性」消融的核心。

## 4. 与上一轮的关系：保留骨架，换掉主路径

### 4.1 保留并升级

| NRB 官方备注恢复 | 保留，但只做**干扰轴**的恢复脚本 | 人为干扰占 20% 运行，不能放弃 |
| DebugLoop | 保留为 Go/No-Go 闸门 | 单任务不计分，但能低成本验证 |
| FLEET 工程检查单 | 降级为**部署检查单**（N 端口、状态隔离、延迟） | 不是创新点，但不做会翻车 |

### 4.2 替换

- **GPR-VLA 主路径 → WLA + AnchorFlow**。GPR 的「谓词/残差/恢复」思想保留为可选的验证器，但不再作为独立模型；否则违反单模型和算力约束。
- **「放置=60% 步骤分」的预算 → 「放置=成功率闸门」的预算**。所有实验先看成功率，再看步骤分。

### 4.3 降级

- **L2L 实验室自采数据**：主路径不用；如果官方确认外部数据允许，再作为增广。
- **TCLB 离线比较**：只做论文消融，不进比赛主路径。
- **FLEET**：工程检查单，不单独占创新点。

### 4.4 砍掉

- 32 任务高保真孪生、自由仿真数据、运行时 MPC、仿真 RL：与 8 周/24GB/180s 不匹配，且单模型约束下收益不确定。
- 布料/拉链/透明物体的全物理建模：用锚点 + 视觉校验 + 重试代替。
- WMA-0 世界模型主路径：训练成本高，延迟不友好；保留为观察项。
- 每任务 LoRA/多个专家：违反「单模型」精神，且 N 端口部署复杂。
- 多模型集成：比赛禁止混用多个模型；论文里也不作为主方法。

## 5. 方案轮廓：一条从语言到锚点、从锚点到动作、从动作到边缘的链

```text
language ──► task/step parser ──► anchor library (K demos, mean g, dispersion σ)
   │                                      │
   ▼                                      ▼
obs (4 RGB + state) ──► anchor head ──► g_hat, confidence c
   │                                      │
   └──────────────► fuse(g_hat, g_retrieval) ──► A0 = build_anchor_chunk(g) + σ0 ε
                                                  │
                                                  ▼
                                   flow bridge (1–2 NFE) ──► action chunk
                                                  │
                                      optional geometric guidance
                                                  │
                                                  ▼
                                   endpoint verifier (wrist) ──► execute / re-anchor
                                                  │
                                                  ▼
                                   edge: distill 1-step, quantize, RTC, N ports
```

三个关键设计：

1. **锚点在相对 EE 动作空间里定义**，不需要显式的物体 6D 位姿。`g` 是「从当前 EE 到释放 EE」的相对位姿；跨回合库存 `g_i` 和动作块 `A_i`；推理时锚点头预测 `g`，或用检索均值 `g_ret`。这避开了透明物体/深度缺失的 3D 估计难题。
2. **流只学残差**。训练时 `A_0 = A^g + σ ε`，目标 `A` 是演示动作；模型学 `v = A - A_0`。推理从 `A^g` 出发，1 步就能得到接近演示的块。锚点噪声 `σ` 让模型学会「锚点不准时怎么修正」。
3. **不确定性门控**。用检索到的 `K` 个锚点的离散度 `σ_ret` 和锚点头的置信度 `c` 决定：源噪声 `σ_0`、NFE、是否开引导、是否回退高斯源。这样不会因为一个坏锚点把整次运行毁掉。

| 风险 | 影响 | 缓解 | 停止条件 |
|---|---|---|---|
| 锚点估计误差大 | 负迁移，成功率下降 | 锚点扰动训练 + 离散度门控 + 高斯回退 | 离线端点误差 > 基线 10% 且真机无提升 |

## 2. 为什么源分布是杠杆

### 2.1 流匹配的最短回顾

WLA 的动作头学一个速度场 `v_θ(a_t, t | o, l)`，把源样本 `a_0` 运到动作 `a_1`：

```text
a_t = (1 - t) a_0 + t a_1
v_target = a_1 - a_0
L = E_{t, a_0, a_1} || v_θ(a_t, t | o, l) - (a_1 - a_0) ||^2
推理：a_{t+dt} = a_t + dt · v_θ(a_t, t | o, l)
```

WLA 取 `a_0 ~ N(0, I)`，4 步 Euler。1 步 Euler 的误差与路径曲率/传输距离相关；源越接近目标，1 步越准。

### 2.2 三种源

| 源 | 形式 | 回答的问题 | 缺点 |
|---|---|---|---|
| 高斯 | `a_0 ~ N(0,I)` | 无 | 传输距离长；1 步误差大 |
| WarmPrior | 上一段动作块 + 噪声 | 「接着刚才往哪走」 | 继承漂移；长程错误累积 |
| 演示锚点（本方案） | 同任务同步骤的释放位姿插值 + 噪声 | 「这一步的正确终点在哪」 | 锚点错时需门控/回退 |

演示锚点的关键：它不是「复制一条演示动作」，而是「用跨回合统计把终点放在正确位置，让流只学当前观测下的残差」。这既保留了生成模型的纠错能力，又给了它一个强几何先验。

### 2.3 传输距离与 1 步误差

设锚点 `a^g` 与目标 `a_1` 的差为 `δ = a_1 - a^g`，源噪声为 `ε`。则：

```text
a_0 = a^g + σ ε
a_1 - a_0 = δ - σ ε
1 步预测：â_1 = a_0 + v_θ(a_0, 0)
若 v_θ 学得准，â_1 ≈ a_1；误差主要来自 δ 的不可观测部分和 σ ε。
```

高斯源的 `||a_1 - a_0||` 通常是动作尺度的 O(1)；锚点源的 `||δ||` 通常小一个量级（同一任务同一步骤的释放位姿方差有限）。这让 1 步在放置段变得可行。

### 2.4 证据（2026 年流策略/边缘论文）

| 论文 | 关键结果 | 对我们的意义 |
|---|---|---|
| WarmPrior（arXiv 2605.13959） | 用上一段动作作源，路径更直，操作任务提升 | 证明「源分布」是有效轴；但它是时间先验，不是任务锚点 |
| SnapFlow（arXiv 2604.05656） | 一步自蒸馏；π0.5 98.75% vs 97.75%；3.3× 延迟；迁移到双臂人形 | 1 步蒸馏可行；但源仍是高斯/原策略 |
| Coda（arXiv 2609.21216） | 端点校正；5 步 71.64→74.68；2.12× 加速；SmolVLA 60.8→69.4 | 端点信息重要；我们直接把端点放进源 |
| One-Step Flow Policy（arXiv 2603.12480） | 自蒸馏；100× 加速；π0.5 RoboTwin | 1 步是边缘趋势 |
| OmniGuide（arXiv 2603.10052） | 统一推理时引导；吸引/排斥能量；无需重训 | 引导是可选第二层 |
| GAF（arXiv 2607.02092） | Q 引导推理；60.0→82.5% 真机；OOD 34.2→49.2% | 测试时引导能救 OOD，但算力高 |

| RTC（arXiv 2506.07339） | 异步动作块；inpainting；对延迟鲁棒 | 边缘块拼接的标配 |
| ActQuant（arXiv 2605.24011） | 亚 4bit 动作引导量化；π0.5 94.8% @ ≤3bit；5.3× 压缩 | 量化可做；但动作头要保精度 |
| DyQ-VLA（arXiv 2603.07904） | 动态量化；内存降至 30.9%；99.5% 性能；1.43× 真机加速 | 边缘量化的参考 |
| Multi-Teacher OPD（arXiv 2610.21522） | 两级 on-policy 蒸馏；LIBERO-40 +22.55%；CALVIN +33.4% | 蒸馏有效；但多教师有合规风险，暂不做主路径 |

来源见第 10 节；检索日期 2026-10-24。

### 2.5 锚点的形式定义

在时刻 `t`，当前 EE 位姿 `T_B^E(t)`，释放时刻 `t+Δ` 的 EE 位姿 `T_B^E(t+Δ)`。定义相对释放位姿：

```text
g = (T_B^E(t))^{-1} · T_B^E(t+Δ) ∈ SE(3)
```

对动作块 `k=0..H-1`，用 smoothstep 插值：

```text
u_k = k / (H - 1)
s(u) = 3u^2 - 2u^3
g_k = exp( s(u_k) · log(g) )        # SE(3) 插值
A^g_k = [trans(g_k), rotvec(g_k), gripper_k, other_dims]
```

`gripper_k` 来自演示的释放时序：放置任务在 `k_rel` 前闭合、之后打开；插入任务在接触后保持闭合。其他维度置零/掩码。

锚点库：

```text
L(τ, j) = { (g_i, A_i, t_i^rel) }_{i=1..K}
ḡ = mean(g_i)
σ_ret = sqrt(mean(||g_i - ḡ||^2))
```

`K` 取 8–32；按容器/位置聚类后取最近簇，避免把不同布局的锚点混在一起。

## 3. AnchorFlow 架构

### 3.1 总览

```text
language ──► task/step parser ──► anchor library L(τ,j)
   │                                      │
   ▼                                      ▼
obs (4 RGB + state) ──► VLM (frozen) ──► anchor head ──► ĝ, c
   │                                      │
   └──────────────► fuse(ĝ, ḡ, c) ──► g ──► build A^g ──► A0 = A^g + σ0 ε
                                                          │
                                                          ▼
                                            flow bridge (1–2 NFE)
                                                          │
                                              optional GeoGuide
                                                          │
                                                          ▼
                                            SVL endpoint check ──► execute / re-anchor
```

### 3.2 锚点库构建（离线）

对每个任务 `τ`、每个评分步骤 `j`：

1. 用 `action.gripper_controls` 的闭合→打开跳变检测释放帧；如果没有跳变（插入/堆叠），用步骤结束帧或 `score_steps` 的语义边界。
2. 取释放帧前 `H` 帧的 EE 位姿，计算 `g_i` 和动作块 `A_i`。
3. 用 `state_d435` / `state_torso` 做坐标一致性检查；异常样本丢弃。
4. 按容器/目标位置聚类（K-means on `g_i` 的平移），每簇保留 8–32 条。
5. 存 `g_i`、`A_i`、`t_i^rel`、簇中心、离散度。

质量控制：

- 释放帧检测的召回/精确率人工抽检 50 条/任务。
- 透明/反光物体的腕部图像做模糊/过曝过滤。
- 动作块归一化用 WLA 的全局 Z-score，避免尺度不一致。

### 3.3 AnchorHead

输入：

- VLM 的 pooled feature `z`（冻结）。
- 当前 EE 位姿 `p`（6D）和夹爪状态。
- 语言 embedding `l`。
- 检索统计 `ḡ, σ_ret`（可选）。

输出：

- `ĝ ∈ R^6`（相对平移 + 旋转向量）。
- `c ∈ [0,1]`（置信度）。

结构：2 层 MLP（hidden 512）或 cross-attention adapter；参数量 1–2M。接在 VLM 特征上，不改变 VLM 权重。

损失：

```text
L_g = || ĝ - g* ||^2
L_c = BCE(c, 1[|| ĝ - g* || < τ])
L_head = L_g + λ_c L_c
```

`g*` 是演示的释放位姿；`τ` 按任务的动作尺度设（如平移 2cm / 旋转 5°）。

推理融合：

```text
g = c · ĝ + (1 - c) · ḡ
```

如果 `c < c_low`，直接用 `ḡ`；如果 `σ_ret` 很大，增大 `σ_0` 并开引导。

### 3.4 Flow Bridge 训练

初始化：WLA-1.0-Base；VLM 冻结；action expert + state projector 可训。

每个训练样本：

```text
A^g ~ L(τ,j)                    # 同任务同步骤的锚点
A   = 演示动作块
σ   ~ {σ_low, σ_mid, σ_high}    # 例如 0.01 / 0.05 / 0.10（归一化空间）
A0  = A^g + σ ε                 # 只扰动位姿维；夹爪维做时间抖动
t   ~ Beta(1.5, 1.0)            # 与 WLA 一致
At  = (1 - t) A0 + t A
v*  = A - A0
L_flow = || v_θ(At, t | o, l) - v* ||^2 · mask
```

可选的额外损失：

```text
L_anchor = || ĝ - g* ||^2 + BCE(c, ...)          # 如果联合训练
L_smooth = || A^g_{k+1} - 2A^g_k + A^g_{k-1} ||^2  # 锚点平滑（离线已保证）
L_cons = || (A0 + v_θ(A0,0)) - (A0 + v_θ(A0,0) + v_θ(Â_0.5,0.5)/2) ||^2  # 1步/2步一致性
```

课程：

1. 先用 `σ_low` 训练 20% steps，让模型适应锚点源。
2. 加入 `σ_mid` / `σ_high`，让模型学会修正坏锚点。
3. 最后混入 10% 高斯源样本，保留回退能力（避免「只会锚点」）。

关键：**不删除高斯源**。模型要同时见过「好锚点、坏锚点、无锚点」，才能在门控回退时不崩。

### 3.5 推理算法

```text
输入：obs, language
1. τ, j = parse_task_step(language, obs)
2. ḡ, σ_ret = retrieve_anchor(τ, j, obs)
3. ĝ, c = anchor_head(z, p, l, ḡ, σ_ret)
4. g = fuse(ĝ, ḡ, c)
5. A0 = build_anchor_chunk(g, obs, j) + σ0 · ε
6. NFE, λ = gate(c, σ_ret, phase)
7. for t in schedule(NFE):
       v = flow(At, t, obs, l)
       if λ > 0 and t > t_guide:
           Â1 = At + (1 - t) · v
           v = v - λ · ∇_{Â1} E(Â1, g, obs)
       At = At + dt · v
8. execute(At)
9. if not verify(wrist_img, g, phase):
       re-anchor with larger σ0 / different cluster / Gaussian fallback
```

### 3.6 几何引导（可选）

能量函数：

```text
E_pos = || p(Â1) - p(g) ||^2
E_rot = || log(R(g)^T R(Â1)) ||^2
E_col = Σ_i max(0, d_safe - d_i(Â1))^2
E_ins = || proj_lateral(p(Â1) - p(g)) ||^2 - α · depth(Â1)   # 插入任务
E = w_p E_pos + w_r E_rot + w_c E_col + w_i E_ins
v ← v - λ ∇_{Â1} E
```

`λ` 由 `c` 和阶段控制：接近段 `λ=0`（别干扰自由路径）；放置/插入段 `λ>0`；`c` 低时 `λ` 小（锚点不可信，别硬拉）。

碰撞距离 `d_i` 用简化几何（桌面平面、容器包围盒、机器人自碰撞 capsule）近似，不做全物理。

### 3.7 终点验证与重锚定

- **几何检查**：末端到 `g` 的平移/旋转误差；夹爪开合状态；是否超过 180s 预算。
- **视觉检查**：腕部相机释放后的图像与锚点库中 K 条演示释放图像的余弦相似度；低于阈值则 flag。
- **语义检查**（可选）：VLM 单帧问答「物体是否在容器内/是否插入」；只在 flag 时调用，省算力。
- **重锚定**：换一个簇的 `ḡ`、增大 `σ_0`、开引导、或回退高斯源；最多重试 2 次。

这不是「学习一个成功分类器」（没有失败标签），而是「用演示释放帧做检索式一致性检查」，数据驱动、可解释、便宜。

## 4. 边缘部署

### 4.1 延迟预算

未知项：目标 GPU 型号、VLM 前缀耗时、N 端口并发数。已知项：6B VLM、4 NFE、30 步块、180s/次。策略：

1. **先测**：在目标 GPU 上测 VLM 前缀、action head 1/2/4 NFE、图像预处理、网络往返。
2. **前缀缓存**：语言 + 首帧的 KV 缓存；图像变化小的时候复用；变化大时重算。
3. **动作头 1 步**：1 NFE 约 1/4 的 action-head 计算；端到端收益取决于前缀占比。
4. **RTC**：执行前 `d` 步时并行算下一块；用锚点作为 committed prefix，inpaint 剩余。
5. **阶段化 NFE**：接近段 1 步；放置/插入段 2–4 步；低置信多 1 步。
6. **预算守卫**：每次运行记录累计耗时；>150s 时降级到 1 步/关闭引导；>170s 时只执行已算好的块。

### 4.2 1 步蒸馏

教师：2 步或 4 步锚点流。学生：同一 action expert，1 步。

方案 A（SnapFlow 式）：学生输入目标时间 `t=1`，直接预测 `Â1`；损失：

```text
L_student = || Â1 - A ||^2 + λ || Â1 - stopgrad(Â1_teacher) ||^2
```

方案 B（Coda 式）：学生预测端点校正，1 步 Euler + 校正头。

方案 C（一致性）：`Â1 = A0 + v_θ(A0,0)`；`Â1_2step = A0 + v_θ(A0,0)/2 + v_θ(Â0.5,0.5)/2`；`L_cons = ||Â1 - stopgrad(Â1_2step)||^2`。

推荐：先 A（简单），再 C（更稳）；只在接近段用 1 步，放置段保留 2 步。

### 4.3 量化

| 位宽 | 范围 | 预期 | 风险 |
|---|---|---|---|
| FP16 | 全部 | 基线 | 显存 |
| W8A8 | VLM + action head | 近无损 | 校准 |
| W4A16 | VLM | 省显存 | 掉点 |
| W4A8 | 激进 | 最快 | 动作头不稳 |

策略：动作头保 FP16/W8A8；VLM 可 W4A16；用 ActQuant 的动作感知校准或 DyQ-VLA 的动态精度；量化后必须做闭环真机/回放测试，不能只看离线 MSE。

### 4.4 前缀缓存 / 连续批处理 / N 端口

- 一个进程加载一个模型；N 个端口共享权重；每端口独立 state（obs 历史、动作队列、RTC 上下文）。
- 语言 + 首帧 KV 缓存；同一 episode 内复用；跨 episode 清空。
- 连续批处理：把多个端口的 VLM 前向合批；action head 按端口并行。
- 延迟记录：每端口每步打点；超预算的端口降级。
- 不要用「多进程多模型」绕过 N 端口；显存和延迟都会炸。

### 4.5 RTC / 异步块

- 动作块 30 步；执行前 `d` 步（如 10）时启动下一块推理。
- 用锚点块作为 committed prefix：已执行的 `d` 步冻结，剩余 `H-d` 步用 flow inpaint。
- 如果新块与旧块冲突大（末端跳变），用 SVL 检查并回退。
- RTC 的收益在长任务/多端口；短任务可能不值得，按任务开。

### 4.6 阶段化计算（PAC）

| 阶段 | NFE | 引导 | 验证 | 理由 |
|---|---|---|---|---|
| 接近 | 1 | 无 | 无 | 自由空间，锚点足够 |
| 抓取 | 2 | 轻 | 腕部 | 精度要求高 |
| 搬运 | 1–2 | 碰撞 | 无 | 路径/避障 |
| 放置/插入 | 2–4 | 强 | 腕部+几何 | 最后闸门 |
| 恢复 | 2–4 | 中 | 语义 | 不确定 |

控制器：`phase` 来自任务/步骤解析；`c`/`σ_ret` 来自锚点；`budget` 来自计时器。三者共同决定 NFE/引导/重试。

### 4.7 资源

- 微调：1×24GB（冻结 VLM）或 1×40/48GB（更快的 batch）。
- 蒸馏：1×24GB。
- 量化：1×24GB。
- 部署：1×24GB 可跑 6B FP16? 6B ≈ 12GB 权重 + KV + 动作头；24GB 可行但紧。W8A8/W4A16 更稳。
- 数据：官方 33k 约 169h；锚点库只存 `g_i/A_i`，几 MB。

## 5. 论文计划

### 5.1 定位

不是「比赛技术报告」，而是「少步流策略的源分布研究」：

> **Source Matters for Few-Step Flow Policies: Demonstration-Anchored Flow Bridges for Real-World Humanoid Manipulation**

| O3 | AnchorHead vs 检索 | 8 任务 | Head 的 `g` 误差 < 检索均值 |
| O4 | 1 步蒸馏 | 8 任务 | 1 步 ≤ 4 步 + 2pp |
| O5 | W8A8/W4A16 | 8 任务 | 掉点 ≤ 3pp |

### 6.2 真机（第 3–8 周）

| ID | 实验 | 任务 | 通过标准 |
|---|---|---|---|
| R0 | 基线 | T27/T10 | 记录成功率/延迟 |
| R1 | 锚点流 4 步 | T27/T10 | 比 R0 高 |
| R2 | 锚点流 1 步 | T27/T10 | 不低于 R1 - 2pp |
| R3 | + UGA | T27/T10 | 回退率 < 15%，成功率不降 |
| R4 | + GeoGuide | T27/T10 | 碰撞/超调下降 |
| R5 | 全量 32 任务 | 全部 | 正式跑 |
| R6 | 量化/RTC | 全部 | 延迟/成功率达标 |

### 6.3 Go/No-Go

- **G1（第 2 周末）**：离线 O1 锚点 1 步端点误差比高斯低 ≥30%；否则改回高斯 + 蒸馏。
- **G2（第 4 周末）**：单任务调试 R1/R2 比 R0 高 ≥5pp；否则缩到 8 任务论文，不冲全量。
- **G3（第 6 周末）**：全量离线 + 1 步蒸馏不掉 >5pp；否则放置段保留 2 步。
- **G4（第 7 周末）**：正式跑成功率 ≥ 基线 + 3pp；否则以论文/技术报告为主。

## 8. 创新点清单（持续迭代）

### 8.1 押注（Bet）

#### A1 AnchorFlow（演示锚点流桥）

- **动机**：WLA 是 4 步流匹配，源是高斯的；放置/插入的最后一步是成功率闸门。让源携带「终点在哪」的先验，1 步就能放对。
- **差异**：不是 WarmPrior 的时间先验，也不是 SnapFlow 的步数蒸馏；是任务/步骤条件化的跨回合演示锚点源 + 锚点扰动训练。生成仍由单模型完成，不复制动作。
- **可行性**：WLA action expert 可在 24GB 微调；锚点库从 33k 数据离线构建；不需要改 VLM 架构（锚点作为初始条件），可选加一个 anchor token。
- **资源**：8 个放置/插入任务，每任务 100–300 条演示；1–2 张 24GB GPU；2–3 周。
- **步骤**：释放检测 → 锚点库 → Flow Bridge 微调 → 离线端点误差 → 单任务调试 → 全量。
- **风险**：锚点估计误差、归一化不一致、负迁移。
- **状态**：**本轮主押注**。

#### A2 UGA（不确定性门控）

- **动机**：坏锚点会把模型带偏；需要知道「什么时候别信锚点」。
- **差异**：用检索离散度 + 锚点头置信度，而不是学一个 critic；门控直接控制源噪声/NFE/引导/回退。
- **可行性**：统计量来自锚点库；阈值在 held-out 校准；无额外训练。
- **资源**：CPU；1 天。
- **步骤**：计算 `σ_ret` → 校准 `c` → 设阈值 → 真机验证回退率。
- **风险**：阈值敏感；新任务分布外。
- **状态**：**押注（A1 的保险）**。

#### A3 Edge 1-step + Quantization

- **动机**：6B + 4 NFE + N 端口 + 180s；边缘要快且稳。
- **差异**：蒸馏「锚点流」而不是「高斯流」；锚点源传输距离短，1 步/量化更稳。
- **可行性**：SnapFlow/Coda/ActQuant/DyQ-VLA 的配方可复用；官方支持 LoRA；24GB 可跑。
- **资源**：1–2 GPU；1 周。
- **步骤**：2 步教师 → 1 步学生 → 一致性损失 → W8A8 → W4A16 → 闭环测试。
- **风险**：蒸馏掉点、量化不稳、动作头精度。
- **状态**：**押注（边缘主路径）**。

#### A4 PAC（阶段化计算）

- **动机**：不是所有步骤都需要 4 步；把算力花在闸门上。
- **差异**：用任务/步骤阶段 + 锚点置信度 + 预算守卫共同决定 NFE/引导/重试；不是固定步数。
- **可行性**：SSG 阶段解析 + 计时器；无额外训练。
- **资源**：CPU；2–3 天。
- **步骤**：阶段标签 → 延迟打点 → 策略表 → 真机调参。
- **风险**：阶段误判；延迟方差。
- **状态**：**保留（A3 的补充）**。

#### A5 论文计划

- **动机**：论文发表是灵感词之一；需要一个可证伪的普遍主张。
- **差异**：把比赛工程上升为「少步流策略源分布」的受控研究；有真实人形 32 任务证据。
- **可行性**：MPU 可在 8 周内完成；RSS 2027/CoRL 2027 时间窗匹配。
- **资源**：写作/实验并行；法务/组委会确认。
- **步骤**：主张 → 消融 → 离线 → 真机 → arXiv → 投稿。
- **风险**：结果不显著；截止；IP。
- **状态**：**押注（与 A1 绑定）**。

### 8.2 保留/升级（Keep / Upgrade）

#### K1 SSG（评分步骤图 → 阶段索引）

- **动机**：32 任务的 `score_steps` 是天然的阶段标签；锚点库和 PAC 需要它。
- **差异**：从「硬状态机」转为「阶段解析 + 诊断」；不直接当奖励。
- **可行性**：`info.json` + 160 条复述；CPU。
- **资源**：1–2 天。
- **步骤**：解析 → 语言匹配 → 阶段标签 → 与锚点库对齐。
- **风险**：谓词噪声；复述歧义。
- **状态**：保留，升级为基础设施。

#### K2 Anchor Library（OPT 升级）

- **动机**：A1 的核心数据资产。
- **差异**：从「放置位姿统计」升级为「可采样的源 + 动作块 + 离散度」。
- **可行性**：数据有 EE 位姿和夹爪时序；离线。
- **资源**：8–32 任务；CPU/几 GB。
- **步骤**：释放检测 → 相对位姿 → 聚类 → QA。
- **风险**：透明物体；释放检测。
- **状态**：升级，核心。

#### K3 ICR（关系检索 → 锚点检索）

- **动机**：OOD 位置/背景；检索同任务同步骤的锚点。
- **差异**：键是相对几何 + 阶段 + 语言，不是外观；检索结果直接当源/先验。
- **可行性**：HNSW；CPU；<5ms。
- **资源**：CPU；1 周。
- **步骤**：键设计 → 建库 → 召回评估 → 融合。
- **风险**：键失败；透明/布料。
- **状态**：升级，A1 的支撑。

#### K4 PGL/SVL（视觉锚点 → 终点校验）

- **动机**：最后一步需要验证；失败要重锚定。
- **差异**：从「2D overlay」升级为「释放帧检索一致性 + 重锚定触发器」。
- **可行性**：腕部相机 + 余弦相似度；无需失败标签。
- **资源**：CPU/GPU；2–3 天。
- **步骤**：释放帧库 → 相似度 → 阈值 → 重试策略。
- **风险**：域差；阈值。
- **状态**：升级，A1 的保险。

#### K5 NRB（官方备注 → 干扰轴恢复）

- **动机**：人为干扰占 20%；不能放弃。
- **差异**：用官方 `human_*_note` 训练/脚本化恢复；重锚定而不是重放。
- **可行性**：备注 + 合成扰动；1–2 周。
- **资源**：合成数据/脚本；GPU。
- **步骤**：解析备注 → 恢复脚本 → 训练 → 真机。
- **风险**：sim-real gap。
- **状态**：保留，但只做干扰轴。

### 8.3 降级（Downgrade）

#### D1 L2L 实验室自采数据

- 主路径不用；外部数据政策未确认。若官方允许，作为增广。
- 状态：降级为可选。

#### D2 TCLB 离线比较

- 只做论文消融，不进比赛主路径。
- 状态：降级。

#### D3 FLEET 工程检查单

- N 端口、状态隔离、延迟记录、并发；不是创新点，但不做会翻车。
- 状态：降级为部署检查单。

#### D4 GPR-VLA

- 谓词/残差/恢复思想保留为验证器；不作为独立模型，避免违反单模型。
- 状态：替换/降级。

### 8.4 砍掉（Cut）

- 32 任务高保真孪生、自由仿真数据、运行时 MPC、仿真 RL：与 8 周/24GB/180s 不匹配。
- 布料/拉链/透明物体全物理：用锚点 + 视觉校验 + 重试代替。
- WMA-0 世界模型主路径：训练成本高、延迟不友好；保留观察。
- 每任务 LoRA/多专家：违反单模型精神，N 端口部署复杂。
- 多模型集成：比赛禁止混用；论文也不作主方法。
- 「多教师 OPD」主路径：训练收益可能大，但合规/算力/时间风险高；只作为论文讨论。

## 9. 风险与合规

| 风险 | 概率 | 影响 | 缓解 | 触发停止 |
|---|---|---|---|---|
| 锚点估计误差 | 高 | 负迁移 | 扰动训练 + 门控 + 回退 | 离线端点误差 > 基线 10% |
| 透明/反光 | 中 | 检索/校验失效 | 腕部近景 + 多视角 + 重试 | 连续 3 次失败 |
| 归一化不一致 | 中 | 训练不收敛 | 用 WLA 全局 Z-score；归一化空间建锚点 | loss 不降 |
| 1 步掉点 | 中 | 成功率下降 | 2 步教师 + 一致性 + 只在接近段 1 步 | 1 步低 >5pp |
| 量化掉点 | 中 | 放置失败 | 动作头 FP16/W8A8；VLM W4A16 | 低 >3pp |
| 单模型合规 | 低 | 取消资格 | 锚点库是数据；一个 checkpoint；不混用 VLA | 官方书面确认前不做多模型 |
| 论文/IP | 低 | 发表受阻 | arXiv 先行；赛后开源；问组委会 | 官方禁止则只发技术报告 |
| 榜单占位误判 | 中 | 策略跑偏 | 只做结构分析；以规则/自测为准 | 不把 29.7% 当上限 |
| 调试槽约不到 | 中 | 无法真机验证 | 提前预约；备选全量小跑 | 两周内约不到则用离线 + 正式跑 |
| 180s 超时 | 中 | 单次失败 | 预算守卫 + 降级 + RTC | 超时率 >5% |

合规要点：

1. **单模型**：锚点库是数据；AnchorHead + Flow Bridge 是一个 checkpoint；确定性几何/检索代码不是「第二个模型」。不调其他 VLA 兜底。
2. **外部数据**：主路径只用官方挑战赛数据；额外 Unitree 集合/实验室数据先问 `challenge_support@unitree.com`。
3. **评测公平**：不探测评测环境、不硬编码任务/位置、不绕过 180s/端口限制。
4. **论文**：不把占位榜单当真实结果；不泄露未公开评测细节；发表前确认。
5. **安全**：真机测试遵守 Unitree 安全规范；急停/限位/碰撞检测不省。

## 11. 开放问题

1. **步骤分公式**：`score_steps` 的具体归一化/加权方式？官方只给权重，是否按时间/完成度折算？
2. **检索/确定性代码是否算「第二个模型」**：锚点库 + 几何引导 + 验证器是否被允许？需要官方书面确认。
3. **调试通道**：单任务测试的预约频率/次数？是否可用于 8 个任务的迭代？
4. **外部数据**：`UnifoLM_G1_Dex1_Dataset` / 实验室自采数据是否允许？影响 L2L 的降级/升级。
5. **论文/IP**：比赛期间能否发 arXiv？权重/数据能否开源？需要书面确认。
6. **榜单真实性**：29.7% 是真实提交还是样例？如果是样例，真实上限未知，策略应更保守。
7. **语言采样**：5 条复述是否均匀采样？是否会出现训练没见过的复述？
8. **头部双目标定**：是否提供内参/外参？锚点头是否需要显式 3D，还是纯 2D 特征即可？
9. **动作空间**：EE 是相对还是绝对？README 说相对；确认归一化统计是否随 checkpoint 提供。
10. **释放检测**：透明/软物体没有明显夹爪跳变时，是否有官方步骤标签可用？
11. **N 端口并发**：官方压测的并发数/超时阈值？RTC 的延迟预算按多少设计？
12. **量化许可**：是否允许 TensorRT/自定义 kernel？部署环境是否固定？

## 12. 一句话押注

**当前最值得押注的是 AnchorFlow：把 WLA 的 4 步流匹配动作专家的起点从高斯噪声换成「任务/步骤条件化的跨回合演示锚点」，用带锚点扰动的 flow bridge 训练、用锚点离散度门控，再蒸馏成 1 步边缘策略——它把「最后一步放对」变成源分布问题，同时服务成功率、OOD 和延迟，并且是一篇关于少步流策略源分布的可发表论文。**
