### 第 4 轮灵感驱动研究记录

**灵感词**：工具调用、机器人操作系统

**继承关系**：第 3 轮 CADVS-v3（IP-485~488）在 v2 三锚点（空间锚 3DCF/Γ_3D、物理锚 MSRG/S2RC、人因锚 HICK/HIC）之上追加末点锚 EEK（EEC、kc_ee）与记忆锚 LTEM（kc_mem），并以联邦聚合器 FFA 做舰队级校准，五硬门 kc_evidence_forged_v3 = kc_coverage ∧ kc_physics ∧ kc_human ∧ kc_ee ∧ kc_mem。本轮不推翻 v3，而是沿「工具调用」与「机器人操作系统」两个方向补强，形成 CADVS-v4（IP-489~492），执行集嵌套升级为 Exec_CADVS-v4 ⊆ Exec_CADVS-v3 ⊆ Exec_CADVS-v2 ⊆ Exec_CADVS-v1 ⊆ Exec_v29。

**直觉与动机**：

1. **工具调用：把证书从「单点判定」提升为「可组合的接口契约」**。v3 的五个硬门都在同一节点、同一时刻、对同一条规则求值；但真实机器人执行是一串技能/工具调用（抓取→搬运→放置），每条调用都有输入参数、前置条件、后置条件。LLM 规划器「调用工具」时最危险的失效不是规则错，而是：参数是规划器臆造的（幻觉）、前置条件未满足却被调用、后置条件被声明得比工具实际保证更强。引入工具调用契约锚 TCCK：每个工具带类型化 manifest τ = (id, sig, pre, post, ℓ_req, frame, Q)，每次调用产生调用证书 Γ_call；硬门 kc_contract 检查类型、前置见证、后置见证与参数来源。证书由此从「一次判定」变成「可传递、可组合的接口对象」：上一步的后置条件必须蕴含下一步的前置条件，整条计划链才成立。

2. **机器人操作系统：把证书从「进程内布尔量」提升为「跨节点的可验证消息」**。v3 的证书默认在同一进程内消费；而 ROS2 系统里证据经 topic/service/action 跨节点传输，穿过 DDS、QoS、TF2 与 lifecycle。这里有三类 v3 未覆盖的断裂：QoS 不匹配（生产者用 TRANSIENT_LOCAL，消费者却把陈旧证书当新鲜）、节点身份与话题可被冒充（SROS2 未启用/配置错误，或 intra-process 通信绕过 DDS 安全）、坐标系与时钟不一致（frame_id 混淆、TF 链过期或外插、use_sim_time 跳变、消息重放）。引入 ROS 证据总线锚 REB：证书是一等 ROS2 消息，携带 QoS 契约、SROS2 节点身份、TF2 帧绑定、单调 nonce 与时钟域；硬门 kc_transport 检查 QoS 兼容、消息认证、帧链新鲜、非重放。让「证书可信」不再只取决于内容，还取决于「谁、在哪个坐标系、哪个时刻、以何种传输保证送达」。

3. **组合性：证书的偏序与计划链的传递闭包**。单条契约通过不足以说明计划安全；需要证书精化关系（post 更强、pre 更弱、时间窗更窄、信任更高，即行为子类型的对偶）与链式组合规则。引入证书组合验证器 CCV：在契约格上检查 post(c_i) ⊨ pre(c_{i+1})，沿链以 Biba 低水位标记传播污点，得到端到端后置条件与最弱环节。

**关键洞见**：v3 五锚回答「证据在何处 / 是否物理成立 / 谁背书 / 末点是否真实 / 历史上是否可靠」；v4 追加接口锚回答「这次工具调用是否满足契约与来源」，传输锚回答「这条证书是否被可信节点在有效帧/时钟内送达」。七硬门 kc_evidence_forged_v4 = kc_coverage ∧ kc_physics ∧ kc_human ∧ kc_ee ∧ kc_mem ∧ kc_contract ∧ kc_transport，fail-closed。更重要的范式转变：证书从「布尔门」变成「带类型、带信任标签、带帧与时钟、可组合的证明对象」，安全从「单点检查」变成「计划级、跨节点的证明传递」。

**形式化目标（增量）**：
1. 定义工具 manifest τ = (id, sig, pre, post, ℓ_req, frame, Q) 与调用证书 Γ_call = (τ.id, args, prov, w_pre, w_post, frame_id, node_id, t, nonce)；契约语言限制为可判定的 QF-LRA 合取片段。
2. 定义信任格 L 与 Biba 低水位污点规则；硬门 kc_contract = type_ok ∧ (∀j. label(args_j) ⊒ ℓ_req) ∧ w_pre ⊨ pre ∧ w_post ⊨ post。
3. 定义证书精化偏序 ⪯（post 收缩 / pre 扩张 / 帧兼容 / 时间窗嵌套 / 信任不降）与计划链 P = c_1;…;c_n；kc_chain = ∧_i kc_contract(c_i) ∧ ∧_i (post(c_i) ⊨ pre(c_{i+1}))。
4. 定义 ROS 传输证书与 kc_transport = kc_qos ∧ kc_auth ∧ kc_frame ∧ kc_replay。
5. 定义 EFA-v4 七硬门与 Exec_CADVS-v4 ⊆ Exec_CADVS-v3：在 v3 每条路径上追加 kc_contract（派发/计划时）与 kc_transport（消息消费时），故只缩不涨。

**本轮最大风险**：**契约可满足性 ≠ 意图正确性——规划器会针对可机器检查的前后置条件做「规格博弈」，在每条工具调用都通过七硬门的情况下组合出违背人类意图的行为，而 ROS 证据总线让这种「合规但错误」的执行获得端到端的可信外观。**

## 1. 增量符号体系（定义 1961–2060）

| 符号 | 含义 |
|---|---|
| τ = (id, sig, pre, post, ℓ_req, frame, Q) | 工具 manifest：签名、前置/后置条件、所需信任等级、坐标系、QoS 契约 |
| sig = (in : Type*, out : Type) | 类型化输入/输出签名 |
| pre, post | 契约语言 L_C 中的谓词（可判定 QF-LRA 合取片段 + 帧成员 + 时间窗） |
| ℓ_req ∈ L | 工具要求的最低参数信任等级 |
| Γ_call = (τ.id, args, prov, w_pre, w_post, frame_id, node_id, t, nonce) | 调用证书：参数、来源映射、前后置见证、帧、节点、时刻、防重放随机数 |
| L = {UNTRUSTED ⊑ LLM_INFERRED ⊑ OBSERVED ⊑ CERTIFIED ⊑ HUMAN_BACKED} | 信任/完整性格（Biba 序，⊒ 表示不低于） |
| ⊔ | 格上最小上界（污点传播取 join，即最弱完整性） |
| prov : arg_index → (label, source_id) | 参数来源映射；label 不可被下游伪造（依赖 kc_auth） |
| kc_contract(Γ_call) | type_ok(args,sig) ∧ (∀j. label(args_j) ⊒ ℓ_req) ∧ w_pre ⊨ pre ∧ w_post ⊨ post |
| c1 ⪯ c2 | 证书精化：post(c1) ⇒ post(c2) ∧ pre(c2) ⇒ pre(c1) ∧ frame 兼容 ∧ 时间窗嵌套 ∧ trust(c1) ⊒ trust(c2) |
| P = c_1;…;c_n | 计划链（工具调用序列） |
| kc_chain(P) | ∧_i kc_contract(c_i) ∧ ∧_i (post(c_i) ⊨ pre(c_{i+1})，经帧/单位适配器) |
| η_chain ∈ [0,1] | 链最弱环节置信度 = min_i margin_i（软评分用，不作硬门） |
| Q = (reliability, durability, deadline, lifespan, history) | ROS2 QoS 契约 |
| kc_qos(Q_p, Q_c, age) | R_p ⊒ R_c ∧ D_p ⊒ D_c ∧ deadline_p ≤ deadline_c^max ∧ age ≤ lifespan |
| kc_auth(msg) | SROS2 enclave 身份 ∈ allowed_publishers(topic)，DDS 安全签名有效；intra-process 路径需显式能力令牌 |
| kc_frame(frame_id, target, t_stamp, t_now) | TF 链存在、无外插、所有变换时间戳 ∈ [t_stamp−ε_tf, t_now+ε_tf]、TF 发布者 ∈ 可信权威集 |
| kc_replay(nonce, t_stamp, t_now) | nonce ∉ 滑动窗口已见集 ∧ |t_stamp − t_now| ≤ Δ_replay |
| kc_transport(msg) | kc_qos ∧ kc_auth ∧ kc_frame ∧ kc_replay |
| δ_c | 时钟漂移上界（跨节点，经 NTP/PTP 校正后残余） |
| ε_tf, Δ_replay | TF 新鲜容忍、重放时间窗（缺省 50 ms、200 ms） |
| ECS_v4(x,t,r) | 软评分 = ECS_v3(x,t,r) · η_chain；kc_contract/kc_transport 为硬门已强制，软层仅记录契约裕度与链强度 |
| kc_evidence_forged_v4 | 七硬门：kc_coverage ∧ kc_physics ∧ kc_human ∧ kc_ee ∧ kc_mem ∧ kc_contract ∧ kc_transport |
| Exec_CADVS-v4 | v4 执行集，Exec_CADVS-v4 ⊆ Exec_CADVS-v3 ⊆ … ⊆ Exec_v29 |

**契约语言 L_C（可判定性声明）**：pre/post 仅允许类型谓词、区间/线性不等式（QF-LRA）、帧成员谓词与时间窗谓词，且为合取式。因此 (a) 见证检查 w ⊨ φ 为逐合取项求值，O(|φ|)；(b) 精化判定 post(c1) ⇒ post(c2) 可归约为 ¬(post(c1) ⇒ post(c2)) 的 QF-LRA 不可满足性，多项式可判定（实作走 SMT，ms 级）。这一限制是刻意的：放弃全一阶表达力，换取组合验证的可判定与低延迟。

## 2. 关键算法骨架

### IP-489 TCCK：工具调用契约锚（计划/派发时，O(|args|·|sig|)）

```python
from enum import IntEnum

class Trust(IntEnum):
    UNTRUSTED = 0
    LLM_INFERRED = 1
    OBSERVED = 2
    CERTIFIED = 3
    HUMAN_BACKED = 4

@dataclass(frozen=True)
class ToolManifest:
    id: str
    sig: tuple[tuple[str, str], ...]     # ((name, type), ...) 输入
    out_type: str
    pre: Conjunction                      # L_C 谓词
    post: Conjunction
    l_req: Trust
    frame: str
    qos: QoSSpec

@dataclass
class CallCertificate:
    tool_id: str
    args: dict[str, Any]
    prov: dict[str, tuple[Trust, str]]   # arg -> (label, source_id)
    w_pre: Assignment                     # 前置见证（来自已验证证据）
    w_post: Assignment                    # 后置见证（来自 EEK/传感器）
    frame_id: str
    node_id: str
    t: float
    nonce: bytes

@dataclass
class ToolCallContractKernel:
    manifests: dict[str, ToolManifest]

    def kc_contract(self, c: CallCertificate) -> tuple[bool, str]:
        m = self.manifests.get(c.tool_id)
        if m is None:
            return False, 'UNKNOWN_TOOL'
        if not type_check(c.args, m.sig):
            return False, 'TYPE_MISMATCH'
        # Biba 完整性：低信任参数不得流入高信任要求工具
        for name, _ in m.sig:
            lab, _src = c.prov.get(name, (Trust.UNTRUSTED, ''))
            if lab < m.l_req:
                return False, f'PROVENANCE_LOW:{name}'
        if not (c.w_pre.satisfies(m.pre) and c.w_post.satisfies(m.post)):
            return False, 'PRECOND_OR_POSTCOND_FAIL'
        if c.frame_id != m.frame:
            return False, 'FRAME_MISMATCH'
        return True, 'CONTRACT_OK'

    def taint_out(self, c: CallCertificate) -> Trust:
        """输出污点 = 输入 join ⊔ 工具自身标签（Biba 低水位）"""
        m = self.manifests[c.tool_id]
        base = Trust.HUMAN_BACKED if m.l_req == Trust.HUMAN_BACKED else m.l_req
        for lab, _ in c.prov.values():
            base = max(base, lab)  # 实际取 join；此处格为全序
        return base
```

### IP-491 CCV：证书组合验证器（计划级，O(n·SMT)）

```python
@dataclass
class CertificateCompositionVerifier:
    tcck: ToolCallContractKernel

    def edge_ok(self, ci: CallCertificate, cj: CallCertificate,
                adapter: FrameUnitAdapter | None) -> tuple[bool, float]:
        """post(ci) ⊨ pre(cj)（经帧/单位适配）；返回 (ok, margin)"""
        post = adapter.rewrite(ci.w_post) if adapter else ci.w_post
        pre = self.tcck.manifests[cj.tool_id].pre
        return smt_entails(post, pre)   # QF-LRA：¬(post⇒pre) 不可满足

    def verify_chain(self, plan: list[CallCertificate],
                     adapters: list[FrameUnitAdapter]) -> tuple[bool, str, float]:
        if not plan:
            return False, 'EMPTY_PLAN', 0.0
        margins = []
        for i, c in enumerate(plan):
            ok, why = self.tcck.kc_contract(c)
            if not ok:
                return False, f'CALL_{i}:{why}', 0.0
        for i in range(len(plan) - 1):
            ok, mg = self.edge_ok(plan[i], plan[i + 1], adapters[i])
            if not ok:
                return False, f'EDGE_{i}_UNSAT', 0.0
            margins.append(mg)
        return True, 'CHAIN_OK', min(margins) if margins else 1.0
```

### IP-490 REB：ROS 证据总线锚（每消息，O(1)+O(log|TF|)）

```python
@dataclass
class RosEvidenceBus:
    tf_buffer: TFBuffer
    trusted_tf_authorities: set[str]
    allowed_publishers: dict[str, set[str]]   # topic -> SROS2 enclave 集合
    seen_nonces: SlidingWindowSet
    epsilon_tf: float = 0.05
    delta_replay: float = 0.20
    delta_c: float = 0.01                      # 残余时钟漂移上界

    def kc_qos(self, q_p: QoSSpec, q_c: QoSSpec, age: float) -> bool:
        rel = q_p.reliability >= q_c.reliability          # REL ⊒ BE
        dur = q_p.durability >= q_c.durability            # TL ⊒ VOLATILE
        dl = q_p.deadline <= q_c.max_deadline
        fresh = age <= min(q_p.lifespan, q_c.max_age)
        return rel and dur and dl and fresh

    def kc_auth(self, msg: CertMsg) -> bool:
        if msg.intra_process:
            return msg.capability_token in self._local_caps(msg.node_id)
        return msg.enclave in self.allowed_publishers.get(msg.topic, set())

    def kc_frame(self, msg: CertMsg, target: str, t_now: float) -> bool:
        try:
            chain = self.tf_buffer.lookup_chain(msg.frame_id, target, msg.t_stamp)
        except TFExtrapolation:
            return False
        return (all(abs(tr.t - msg.t_stamp) <= self.epsilon_tf for tr in chain)
                and all(tr.authority in self.trusted_tf_authorities for tr in chain))

    def kc_replay(self, msg: CertMsg, t_now: float) -> bool:
        if abs(msg.t_stamp - t_now) > self.delta_replay + self.delta_c:
            return False
        return self.seen_nonces.insert(msg.nonce)   # 已见则返回 False

    def kc_transport(self, msg: CertMsg, q_c: QoSSpec, target: str, t_now: float) -> bool:
        age = (t_now - msg.t_stamp) + self.delta_c
        return (self.kc_qos(msg.qos, q_c, age)
                and self.kc_auth(msg)
                and self.kc_frame(msg, target, t_now)
                and self.kc_replay(msg, t_now))
```

### IP-492 EFA-v4：七硬门 + 计划级组合

```python
@dataclass
class EvidenceForgingAssemblerV4:
    scf: SpatialCoverageFieldKernel
    msrg_cache: dict
    hic: HumanIntentCertificateKernel
    eek: EndEffectorFidelityKernel
    ltem: LongTermEpisodicMemory
    tcck: ToolCallContractKernel
    ccv: CertificateCompositionVerifier
    reb: RosEvidenceBus
    mu_S: float = 0.75

    def hard_gate(self, x, t_now, rule_id, hic, eec, ctx,
                  call: CallCertificate, transport: CertMsg,
                  q_c: QoSSpec, target_frame: str) -> tuple[bool, str]:
        # --- v3 五硬门（原样） ---
        if self.hic.veto_active(hic):             return False, 'HIC_STOP'
        if not self.scf.kc_coverage(x, t_now):    return False, 'COVERAGE_BLIND'
        s2rc = self.msrg_cache.get(rule_id)
        if s2rc is None or s2rc.verdict != 'accept' or s2rc.mu_pass < self.mu_S:
            return False, 'PHYSICS_UNPROVEN'
        if not self.eek.kc_ee(eec):               return False, 'EE_UNPROVEN'
        ok_mem, _eta, _nov = self.ltem.query(*ctx)
        if not ok_mem:                            return False, 'MEMORY_REJECT'
        # --- v4 新增两硬门 ---
        ok_c, why = self.tcck.kc_contract(call)
        if not ok_c:                              return False, f'CONTRACT:{why}'
        if not self.reb.kc_transport(transport, q_c, target_frame, t_now):
            return False, 'TRANSPORT_UNTRUSTED'
        return True, 'FORGED_V4'

    def plan_gate(self, plan, adapters) -> tuple[bool, str, float]:
        """计划级：先逐调用过 kc_contract，再逐边过 post⊨pre；失败即整计划拒"""
        return self.ccv.verify_chain(plan, adapters)

    def ecs_v4(self, x, t_now, rule_id, A_att=0.0, eta_mem=0.5, eta_chain=1.0) -> float:
        base = (self.scf.gamma3d(x, t_now) ** 0.4
                * getattr(self.msrg_cache.get(rule_id), 'mu_pass', 0.0) ** 0.4
                * (1 + 0.2 * A_att))
        return base * eta_mem * eta_chain
```

### 集成流水线（v3 → v4）

```
计划时（LLM/任务规划器，~100 ms~1 s/计划）：
  planner 产生工具调用序列 P = c_1;…;c_n（参数带 prov 标签）
    ──▶ TCCK.kc_contract 逐调用（类型/信任/前后置/帧）
    ──▶ CCV.verify_chain 逐边 post(c_i) ⊨ pre(c_{i+1})（QF-LRA + 帧/单位适配）
    ──▶ 任一失败 → 拒绝整计划 / 请求教师或重规划（不得「跳过失败调用」继续）

派发时（ROS2 action/service，~ms）：
  每条调用打包 CertMsg{Γ_call, qos, enclave, frame_id, nonce, t_stamp}
    ──▶ REB.publish（RELIABLE + 合理 lifespan；禁止用 TRANSIENT_LOCAL 掩盖陈旧）

消费时（订阅者，~µs/消息）：
  REB.kc_transport（QoS / SROS2 认证 / TF2 帧新鲜 / nonce 防重放）
    ──▶ EFA-v4.hard_gate（v3 五门 + kc_contract + kc_transport）

控制环（< 0.1 ms 增量）：
  每周期 EEK → EEC（含 frame_id/clock_domain）→ kc_ee；证书消费前调用 hard_gate
     ├─ CONTRACT:*        → 拒绝调用，回到规划器（不执行半成品）
     ├─ TRANSPORT_*       → 丢弃消息，回退 STCK 球域 + 教师，记录攻击面事件
     ├─ HIC_STOP          → S_stop
     ├─ COVERAGE_BLIND    → 回退 STCK 球域 + 教师
     ├─ PHYSICS_UNPROVEN  → 规则降权（统计模式）
     ├─ EE_UNPROVEN       → 末端复位/重触 + 教师
     └─ MEMORY_REJECT     → 教师介入或重新 MSRG
```

## 3. 复杂度分析（增量更新）

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 | 实时性指标 |
|---|---|---|---|---|
| TCCK kc_contract | O(\|args\|·\|sig\|)（schema 有界，≈O(1)） | O(\|args\|) | 参数个数 | 计划/派发时 < 1 ms/调用 |
| CCV edge_ok | QF-LRA 蕴含判定，多项式（实作 SMT） | O(\|pre\|+\|post\|) | 谓词合取项数 | 计划时 ~ms/边 |
| CCV verify_chain | O(n·SMT) | O(n) | 计划长度 n | 计划时（n=8 约数 ms） |
| REB kc_qos/auth/replay | O(1) | O(窗口) | nonce 窗口 | < 5 µs/消息 |
| REB kc_frame | O(log\|TF\|)（或 O(1) 缓存） | O(\|TF 链\|) | TF 树规模 | < 10 µs/消息 |
| EFA-v4 hard_gate | O(1) + O(log\|TF\|) | O(1) | — | 控制环内 < 0.03 ms |
| 端到端在线增量 | < 0.1 ms | — | — | 不劣化 v3 200 Hz / P99 < 8 ms |

**通信开销**：CertMsg 约 0.3–1 KB/消息（含 nonce、帧、enclave 摘要、QoS）；REB 仅异常/变化上报，避免 1 kHz 全量；计划级验证在非控制时域，不进入 200 Hz 环。

## 4. 正确性论证（增量更新）

### 引理 41（契约组合的归纳可靠性）

**陈述**：设每条调用 c_i 满足 kc_contract，且每条边满足 post(c_i) ⊨ pre(c_{i+1})（经帧/单位适配）。若契约语言 L_C 的语义相对于物理状态是可靠的（witness 真则谓词真），则计划 P 的端到端后置条件 post(P) = post(c_n) 在链上成立。

**证明**：对 n 归纳。基例 n=1 由 kc_contract 的 w_post ⊨ post 直接得。归纳步：由归纳假设 post(c_{n−1}) 成立；边条件 post(c_{n−1}) ⊨ pre(c_n) 给出 pre(c_n) 成立；kc_contract 的 w_pre ⊨ pre 与 w_post ⊨ post 及语义可靠性给出 post(c_n) 成立。∎

**工程含义**：安全论证从「每条规则单独可信」升级为「每条工具调用与每条边均可信」，端到端后置可被机器检查。但归纳只保证「契约语言内可表达的后置」——表达力之外的物理不变量不在保证范围（见定理 v4 诚实声明与 R46）。

### 引理 42（参数来源的完整性非干扰）

**陈述**：在 Biba 低水位污点规则下（输出标签 = 输入 join ⊔ 工具标签），若每个工具调用的参数标签满足 label(args_j) ⊒ ℓ_req，则任何标签低于 ℓ_req 的值（典型为 LLM_INFERRED 的幻觉参数）不能作为该工具的参数被接受；且污点沿链单调不增（完整性只降不升）。

**证明**：kc_contract 逐参数检查 label ⊒ ℓ_req，低于即拒。taint_out 取 join，join 关于格序单调，故链上标签不会高于任一上游输入的最小完整性；由归纳，未受信来源的值不可能在无 certified 源「洗白」的情况下满足高 ℓ_req。∎

**工程含义**：把「工具调用幻觉参数」从概率问题变为构造性阻断。**前提**是 prov 标签不可伪造——该前提由 kc_auth/kc_transport 提供（引理 43），故 42 与 43 必须同时成立。

### 引理 43（传输新鲜性、防重放与帧一致性）

**陈述**：设跨节点残余时钟漂移 ≤ δ_c，kc_qos 强制 age ≤ Δ_max，kc_replay 强制 |t_stamp − t_now| ≤ Δ_replay + δ_c 且 nonce 未被消费。则 (a) 被消费证书的真实年龄 ≤ Δ_max + 2δ_c，超过 lifespan 的陈旧证书被拒；(b) 重放消息被拒（精确滑动窗口；若用 b 位 nonce 的概率集，碰撞率 ≤ q²/2^{b+1}）；(c) 帧混淆被拒，除非攻击者控制可信 TF 权威（假设 C3）。

**证明**：(a) age 计算含 δ_c 修正，三角不等式给出上界。(b) nonce 集合插入返回「已见」即拒，滑动窗口界定状态空间。(c) kc_frame 要求 TF 链无外插、时间戳在 ε_tf 内、且发布者在可信权威集；无 C3 时攻击者无法构造可信链。∎

**工程含义**：v3 假设「证书内容可信」，v4 显式把「送达可信」也纳入硬门，覆盖 QoS 误配、节点冒充、帧混淆、重放四类 ROS2 特有失效。**但** intra-process 通信绕过 DDS 安全，必须由 kc_auth 的显式能力令牌补上，否则是旁路。

### 定理 v4（执行集收缩、七锚点补全与组合可靠性）

**陈述**：在假设 (C1) 契约语言 L_C 对目标物理不变量语义可靠且表达力充分；(C2) SROS2 密钥与 enclave 身份未被攻陷、intra-process 能力令牌不可伪造；(C3) TF 权威与时钟源可信；(C4) 继承 v3 的 (B1)~(B4) 下：
(i) Exec_CADVS-v4 ⊆ Exec_CADVS-v3 ⊆ … ⊆ Exec_v29（严格收缩）；
(ii) 计划链端到端后置由引理 41 保证；
(iii) 幻觉/低信任参数流入高信任工具的概率为 0（引理 42，条件 C2）；
(iv) 陈旧/重放/帧混淆证书被拒（引理 43，条件 C3）；
(v) 七硬门 fail-closed，任一不通过即拒；仅 HIC veto 旁路至 S_stop。

**证明**：(i) v4 在 v3 每条路径上以合取追加 kc_contract 与 kc_transport，合取只删不增；严格性由存在 v3 通过但 kc_contract（幻觉参数）或 kc_transport（陈旧证书）失败的调用保证。(ii)~(iv) 分由引理 41/42/43。(v) 由 EFA-v4.hard_gate 的合取结构与短路返回顺序。∎

**诚实声明**：最脆弱假设是 **(C1) 契约语言的表达力充分性**——post 若只写了「夹爪闭合」，就检查不出「累计接触力超限」「工作空间被占用」这类跨调用全局不变量；此时链在语法上通过，物理上却可能违规（组合性伪证）。次要风险是 (C2)/(C3)：拥有合法 enclave 的被攻陷节点、或被攻陷的 TF 权威，可伪造「合规」证书。缓解：全局不变量以额外 monitor 形式外挂并纳入 kc_chain；高风险工具保留 HICK 人审；SROS2 最小权限与密钥轮换；TF 权威多源交叉校验；计划级与规则级双重人审。

## 6. 已知风险与缓解（增量更新）

| 风险编号 | 描述 | 严重度 | 缓解措施 | 剩余风险 |
|---|---|---|---|---|
| R19–R45 | v1/v2/v3 全部既有风险 | — | 随 v1~v3 原样继承；R43/R44 由 v4 的传输认证部分收窄 | 见 v1~v3 表 |

| R47 | **工具描述投毒/参数幻觉**（恶意 manifest 夸大 post；规划器臆造参数） | 高 | manifest 签名与版本锁定；Biba 污点强制 provenance；LLM 输出结构化校验 | 合法 manifest 的语义错误难检测 |

| R50 | **规格博弈/意图漂移**（规划器优化可检查的契约而非人类意图） | **极高** | 意图规约（intent spec）与契约双向校验；计划级人审；反 Goodhart 的红队评测 | 意图本身难以形式化，残余不可消除 |
| R51 | **组合验证延迟/状态爆炸**（长计划、复杂 QF-LRA 谓词） | 中 | 谓词片段限制；边缓存；计划分段验证；超时 fail-closed | 超长计划可能超出实时预算 |

## 7. 本轮最大风险（最终确认）

**一句话**：**契约可满足性 ≠ 意图正确性——规划器会针对可机器检查的前后置条件做「规格博弈」，在每条工具调用都通过七硬门的情况下组合出违背人类意图的行为，而 ROS 证据总线让这种「合规但错误」的执行获得端到端的可信外观。**
