# 第 3 轮（本循环）｜S3M：让语义地图成为评分步骤的状态总线

> 检索/复核日期：2026-10-25（UTC）。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测；本轮未检索到第二个更可能的同名 UniBot。状态文件上一版是第 7 轮 PILOT-GPR，本循环按用户指定记为第 3 轮，内容上是它的第 8 次迭代。三个灵感词是「语义地图」「UniBot」「场景落地」。我的主判断是：**语义地图不该做成通用 3D SLAM，而应做成“评分步骤条件化的 2.5D 对象关系图”（S3M）——它同时承担目标 grounding、步骤谓词验证、放置槽位选择、人为干扰后的地图差分恢复；它不是又一个规划器，而是把上一轮 SSG/PGL/OPT/SVL 串起来的缺失状态总线。**

## 0. 本轮先核实：八个事实与一个纠正

### 0.1 榜单：8 条展示，头部 29.7%，但仍高度像演示数据

`leaderboard.html` 现在能渲染出 8 条记录（[S2][S3]，检索 2026-10-25）：

| 排名 | 模型/用户 | 平均成功率 | 步骤分 | 平均时长 |
|---:|---|---:|---:|---:|
| 1 | MolmoAct2 / DexHacker | 29.7% | 39.0 | 44.02s |
| 2 | WALL-OSS-0.5 / Generalist Robotics | 28.5% | 38.9 | 43.74s |
| 3 | DreamZero / World Model Lab | 27.9% | 37.9 | 44.59s |
| 4 | Spirit-v1.5 / VLAGO | 25.9% | 34.4 | 45.19s |
| 5 | DM0 / Embodied AI Institute | 23.5% | 31.7 | 45.11s |
| 6 | PI-0.5 / RoboReasoner | 22.8% | 30.6 | 43.88s |
| 7 | GigaBrain-0 / xembody | 22.6% | 29.5 | 43.76s |
| 8 | GR00T N1.5 / Humanoid Dynamics | 20.5% | 28.1 | 44.71s |

但必须把“展示值”和“真实结果”分开：

- `leaderboard_data.json` 仍写着 `generated_from: "gen_leaderboard.py"`，数据发布时间是 2026-10-08；页面底部仍写「即将发布 / Coming Soon」[S2][S3]。
- 因此这 8 条更像**带真实模型名的 UI 演示/种子数据**，不能据此做真实轴级归因。用户说的“榜首不到 30%”与展示值一致，但它只能当目标参照，不能当“已知瓶颈”的证据。
- 可以用的真实信息是**模型家族**：MolmoAct2、WALL-OSS-0.5、DreamZero 都是公开模型，论文里的域内成绩远高于 30%——MolmoAct2 在 Franka 五个任务上 zero-shot 平均 87.1%[S17]；WALL-OSS-0.5 在 15 个真机任务上微调后平均 60.5%[S20]；DreamZero 在环境/任务泛化上比强 VLA 高 2×[S22]。**这说明 UniBot 的 ~30% 不是“模型不会抓放”，而是“换场景、换任务状态、换本体后，泛化与状态保持崩了”。**
- 如果这些条目最终被官方确认为真实提交，那么头部方案分别是：action-reasoning VLA（MolmoAct2）、gradient-bridged VLA（WALL-OSS-0.5）、world-action model（DreamZero）。它们的共同短板见 0.6。

### 0.2 手册：每任务 10 次，5 类泛化各 2 次；排名先看成功率

英文/中文参赛手册明确（[S7][S8]，检索 2026-10-25）：

- 每个任务执行 **10 次独立运行**；10 次里包含 5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰），**每类各出现 2 次**。所以 32×10 = **320 个计分 trial**。
- 实时榜单按 **32 个任务的总平均成功率**排序；成功率相同，按 **总平均步骤分**；仍相同，**提交日期更早**的靠前。
- 单次真机执行上限 **180 秒**，超时记失败，并按执行情况计算步骤分。
- 只设通才模型赛道：一个模型完成全部 32 个任务，不得按任务混合多个模型；模型架构不限（VLA、World Model 均可）。
- 另有**不计分单任务测试通道**，只测 1 个任务，用于粗略验证能力。

**这是本轮最重要的纠正：**上一轮 PILOT 把“步骤分”当成与成功率并列的主目标；实际排名是**成功率优先、步骤分只在打平时起作用**。终局放置仍然是成功闸门（成功=所有步骤完成），但不应为了多拿部分分而牺牲整任务成功率。S3M 的设计目标也要随之调整：**先保 success，再保 step**。

### 0.3 数据：32k/169h；HangCup 1043 条；数据集里有相机/躯干位姿

- 官方任务页：32 个任务、32,000 条演示、169 小时[S1]。
- HuggingFace collection：32 个数据集，约 32k 条、169h[S11]；HangCup 实测 **1,043 条 / 194,564 帧 / 30fps / 四路 640×480 相机**，`lastModified` 2026-10-14[S12][S13]。
- 数据集字段里除了四路图像，还有 `observation.state.state_d435`（头部 D435 相机在 base 系的 6D 位姿）、`observation.state.state_torso`（躯干 6D 位姿）、`left/right_ee_pose_gripper_base`、`left/right_ee_pose_gripper_torso` 等[S13]。
- **API 不提供 depth、不提供相机标定、也不提供 `state_d435`/`state_torso`**；它只给四路 RGB、双臂关节/EE base 位姿、夹爪、`lower_body`（15 维，最后三维是 waist yaw/roll/pitch）和 language[S9]。但头部相机与躯干是固定安装，`lower_body` 又给了 waist 三关节；用 G1 URDF 做前向运动学，可以把头部相机位姿算到 base 系。`head_stereo_left/right` 若确为已标定双目，还可用立体匹配得到米制深度。**这是 S3M 在“无深度 API”下仍可行的关键技术支点。**

### 0.4 API：四路 RGB、EE base、N 个连续端口、延迟会被记录

`unibot_submission` v2（最近提交 2026-08-21）[S9][S10]：

- 必须实现 `metadata`、`get_action(obs)`、`reset()`；`metadata` 必填 `control_space`、`data_keys`、`obs_chunk_size`、`action_chunk_size`、`token` 五项。
- 观测是四路 RGB + 双臂关节/EE base 位姿 + 夹爪 + `lower_body` + `observation.language`；language 是 episode 内不变的单个字符串。
- 动作空间 `joint` 与 `ee` 互斥；`obs_chunk_size`、`action_chunk_size`、`image_resize` 由选手定；v2 支持观测跳帧堆叠和测试端图像缩放。
- 评测跨 **N 台测试机器人**，选手须从 **8765 开始暴露 N 个连续端口**，每端口独立服务一台机器人；每端口的 `reset` 与历史状态必须严格隔离。
- 平台会记录每步响应延迟、延迟稳定性、动作统计规律，并可能随结果公布；异常交互会被纳入可信度判断。

对 S3M 的含义：**完全可以在策略线程之外跑一个 2–5Hz 的地图线程**，把结果缓存给 `get_action`；动作 chunk 8–16，地图不需要每步全量重建。地图线程的延迟不直接进入 `get_action` 的 p99，但共享 GPU 时要限流。

### 0.5 人为干扰有逐任务备注，而且每任务有 2 次 human 运行

`tasks_v2/<slug>/info.json` 的 `generalization` 字段给出 `human_1_note`、`human_4_note`、`unseen_object_3`[S14][S15][S16]。例如：

- T27 StackBowls：human_1「把粉色碗向下移动」；human_4「叠了第二个之后拿下第二个」（先叠后撤=undo）。
- T19 ZipUp：human_1「把包向左边移动」；human_4「拉上拉链之后拉开」。
- T10 PlugCharger：human_1「抓插头前进行移动」；human_4「将插头拔起」。
- T12 Unlock：human_1「锁向左移动」；human_4「中途把锁拿走」。

编号含义（轴编号还是试次编号）官方未解释；但内容本身是可直接场景化的干扰剧本：多数是“对某个对象做一次 1-DOF 平移”或“在某步完成后撤销它”。现在手册又确认每任务有 2 次 human 运行（占 20%），所以**地图差分恢复有明确靶子**：不需要猜 human 会怎么干扰，官方备注已经给了剧本。

### 0.6 头部模型的自述瓶颈：不是不会抓，而是没有持久状态与闭环校验

- **MolmoAct2**：action-reasoning VLM + flow-matching action expert；一次规划 10–30 步的动作块并整段执行，**中途不重新推理**，遇到障碍/变化不能及时调整；开箱只对 SO-100、bimanual YAM、Franka 验证，换 humanoid 需要额外训练；基础模型单次动作约 180ms，Think 版约 790ms[S17][S18]。
- **WALL-OSS-0.5**：4B VLA，20+ 本体、百万级轨迹预训练；但作者明确写**单帧图像输入、无时序记忆**，固定 26 维动作表示，长程/状态跟踪受限[S20][S21]。
- **DreamZero**：14B world-action model，视频扩散 + 动作联合建模，7Hz、约 150ms/chunk；泛化强但模型重，且没有显式的对象状态验证器[S22][S23]。

共同点：**它们都能“从当前帧生成动作”，但都没有一个显式的、可查询的“任务做到哪一步、东西现在在哪、有没有被人动过”的状态层。** 这正是 S3M 的切入点，也是为什么它不需要替换基座模型。

### 0.7 语义地图/对象记忆的文献已经成熟，但缺口正好在 UniBot 的评分方式

- **OCC4M**：object-centric 4D memory，持久对象轨迹 + 世界坐标 + containment 关系；记忆成功率 96.6%、端到端 88.9%，对比 full-history VLM 的 54.6%/57.7%；视角切换后 100%/98%，full-history 接近 0[S24]。
- **FOUND-IT / FOUND-IT++**：无标定单目 3D scene graph，实时 4–7fps（3090；Jetson Thor 4Hz）；支持 open-set 查询、变化检测、多 session 建图、场景重排；但抓取成功率只有 50%，作者归因于没有主动深度/闭环[S25][S26]。
- **MomaGraph**：state-aware、task-oriented scene graph，Graph-then-Plan，在基准上 71.6%（+11.4）[S27]。
- **OMAR**：开放世界实例级 3D scene graph + 多属性推理，让未见物体按场景潜规则放置，无需类特定重训[S28]。
- **SDPP**：语义密度 + 可达性地图做多物体放置，明确把“未来可放置空间”纳入评分[S29]。
- **GEM**：patch-level semantic map 做开放词表 pick/place，少样本/零样本；但动作空间是 SE(2)，复杂任务受限[S30]。
- **Semantic-3DGS**：可刷新的 3D 语义 grounding，长程 60% vs PointVLA 40%、DexVLA 28%；重 clutter 74% vs 单视角 52%；75cm 高度偏移下仍 75%[S31]。
- **MemoryVLA / Mem4Act**：显式记忆在长程任务上 +11.8~26pp[S32][S33]。

**缺口**：这些工作大多服务导航、移动操作或通用规划；没有把地图直接编译成“评分步骤谓词”，也没有用地图差分回退评分步骤。UniBot 的成功定义是“所有步骤完成”，这恰好是语义地图最该发光、却还没被占住的位置。

### 0.8 因此本轮要修剪什么

- **步骤分从“并列主目标”降为“tie-break 目标”**；终局放置仍是 success 闸门，但不为部分分牺牲整任务成功。
- **通用 3D SLAM / 全场景高保真重建：砍**。桌面任务 + 无深度 API + 180s，不值得；用 2.5D 对象关系图。
- **跨 episode 静态地图默认开启：降级为可选**。评测是否保持桌面/机位未知；默认只做 episode 内动态图，静态层要过“场景指纹”才复用。
- **ICR 大而全：降级为 map-keyed retrieval**。检索键由 S3M 的关系图给出，K 取 3–4，不再单独维护一套重型检索。
- **全 32 任务高保真孪生、自由仿真数据、运行时 MPC、仿真 RL、每任务 LoRA：继续砍**。
- **“语义地图当 planner”：不做**。地图只做 state bus / verifier；抓放仍由 VLA 负责。

## 1. 三个灵感词，各自钉到 UniBot 的事实上

### 1.1 语义地图：从“建图”改成“评分状态机”

通用语义地图回答的是“场景里有什么、在哪”；UniBot 真正需要回答的是四件事：

1. **现在到第几步？**（评分步骤状态）
2. **目标/容器/工具现在在哪？**（对象 grounding）
3. **这一步的谓词成立了吗？**（防假完成）
4. **刚才有没有外部变化把已完成步骤弄坏了？**（人为干扰/undo）

所以 S3M 不是“更漂亮的 3D 地图”，而是：

```text
S3M = 任务条件化的 2.5D 对象关系图
    + 从公开 score_steps 编译出的步骤谓词
    + 地图差分（谁被移动/撤销/遮挡）
    + 容器局部槽位占据图
```

它的粒度由任务决定：叠碗只需要“碗 1/2/3 的上下关系 + 桌面坐标”；插插头需要“插排、插头、插座孔、插入方向”；叠毛巾只需要“毛巾的粗位姿 + 折叠阶段”，不需要重建布料。**地图只跟踪与当前步骤有关的对象和关系**，这既降延迟，也避免被背景/干扰物淹没。

为什么是 2.5D 而不是 full 3D：

- 桌面任务的主 workspace 是一个支撑平面；`on / in / left-of / stacked` 这些谓词用“平面坐标 + 高度/支撑关系”就够。
- API 没有 depth；2.5D 可以用头部双目、桌面平面单应、或单目深度 + 桌面尺度恢复，失败时退化到 2D 锚点。
- 2.5D 图更小、更稳、更容易做可解释日志；full 3D 点云/网格在 180s 和网络观测下性价比低。

为什么不是“端到端 VLA 自己学状态”：

- 头部模型已经证明：单帧 VLA 没有持久状态（WALL 自述），action chunk 又没有中途修正（MolmoAct2 自述）；让 VLA 隐式学“第几步/谁被移动”既样本低效，也不可审计。
- 显式图可以把“状态”从模型里拿出来，变成可检查、可回退、可注入的接口；这对比赛调试和模型卡合规都更友好。

### 1.2 UniBot：语义地图跨五轴，但基座模型仍是主角

S3M 对五类泛化的作用不是均匀的：

| 泛化轴 | S3M 的作用 | 局限 |
|---|---|---|
| 位置 | 对象/容器用 base 系坐标跟踪；放置点用容器局部系，不依赖绝对像素 | 基座移动/相机外参变化时要重定位 |
| 干扰物 | 显式节点 + 关系，目标 grounding 不被 clutter 淹没；可把干扰物标为 non-task | 检测器可能把干扰物认成目标 |
| 背景 | 用几何关系（on/in/left-of）而不是背景纹理；换桌布不影响图结构 | 纯视觉检测仍可能受强纹理影响 |
| 未见物品 | open-vocab 检测 + 角色绑定（target/receptacle/tool），不依赖训练类别 | 透明/反光/软物体检测不稳 |
| 人为干扰 | 地图差分检测“谁被移动/撤销”，回退步骤并重试 | 人手遮挡/快速移动/出视野会漏检 |

但必须诚实：**地图不会抓，也不会拧瓶盖。** 基座 VLA 仍然是主力；S3M 是乘数/保险丝。按当前展示的 29.7% 基线，S3M 的现实目标不是“翻倍”，而是 +3~5pp 的整任务成功率——这已足够在 320 trial、SE≈2.6pp 的榜单上改变名次。若基座在某个任务上连终局步都到不了（q 很低），地图的收益会被 q 打折。

### 1.3 场景落地：不训练新模型，靠“现场建档 + 自校准 + 可退化”落地

“场景落地”在 UniBot 里有三层含义：

1. **换场景不换模型**：32 个任务、5 类泛化、多个机器人；不可能为每个场景训一个模型。S3M 在 `reset()` 后现场建图，只加载任务 schema，不更新权重。
2. **换机器人不换标定流程**：头部相机与躯干固定，`lower_body` 给 waist 三关节；用 URDF 前向运动学 + 桌面平面 RANSAC 自校准。若 `head_stereo_left/right` 已标定，直接立体匹配；若没有，退化到单目深度 + 桌面尺度。
3. **换场景可复用**：静态层（桌面、架子、固定容器）可缓存；动态层（任务物体）每 episode 重建。是否复用静态层由“场景指纹”（桌面平面系数、静态物位姿、相机位姿）决定；指纹不匹配就重建，绝不硬套。

部署上，S3M 是**异步地图线程 + 策略线程**：

```text
策略线程（get_action，目标 p99 <100ms）
  └─ 读缓存：当前步骤、目标锚点、槽位候选、恢复标志
地图线程（2–5Hz）
  └─ 检测/双目/关联/谓词/差分 → 更新缓存
```

这样地图的 100–300ms 不会直接卡住 30Hz 策略；动作 chunk 8–16 给地图留出更新窗口。N 个端口各自维护自己的动态图，静态标定可只读共享。

## 2. 本轮主判断：S3M 是“评分状态总线”，不是又一个规划器

### 2.1 一句话

**把语义地图从“世界表示”改成“评分状态表示”：S3M 只回答“到第几步、东西在哪、谓词成不成立、有没有被外部改动、下一步放哪个槽”，抓放仍交给 GPR-VLA；它把上一轮的 SSG/PGL/OPT/SVL 从四个各自为战的模块，变成共享同一张对象关系图的状态机。**

### 2.2 它具体替代/升级了什么

| 上一轮组件 | 本轮定位 | 变化 |
|---|---|---|
| SSG 评分步骤图 | S3M 的 **schema 编译器** | 步骤文本 → 谓词模板；不再依赖纯学习谓词头 |
| PGL 放置目标阶梯 | S3M 的 **槽位图 + 锚点渲染** | 从“检测到容器”升级为“容器局部占据图 + 语义槽位” |
| OPT 少样本位姿迁移 | S3M 的 **位姿先验** | 容器系释放位姿统计仍是核心；地图负责在线跟踪容器 |
| SVL 落点闭环 | S3M 的 **谓词验证 + 修复** | 从“放完看稳定”升级为“图差分 + 步骤回退 + 重试” |
| ICR 上下文检索 | **MKT：map-keyed retrieval** | 键由 S3M 图/相位给出；K 降到 3–4；不再单独做重型检索 |
| NRB 官方备注恢复 | **MDR 的训练/回放脚本** | human 备注直接变成图差分恢复对 |
| TLE 数据引擎 | **S3M 自动标注器** | 用图谓词自动产对象状态/关系/步骤边界标签 |
| GPR-VLA | **唯一学习基座** | 不变；S3M 是确定性代码 + 数据，不是第二个任务模型 |

### 2.3 预期收益：先算清楚，再决定押不押

用当前展示的 29.7% 当参照（仅作算术，不作事实）：

- 人为干扰占 20%（64/320）。若 human 子集基线 15%，MDR 把它拉到 35%，全局 +4.0pp。
- 放置类任务约占 60%（19/32）。SPM 让这些任务 +5pp，全局 +3.0pp。
- 假完成/未验证失败占失败的一部分；若只占 10%，S3M 抓住一半，全局 +1.8pp。
- 背景/未见物品占 40%；S3M 的几何关系 + open-vocab 角色绑定 +2~3pp，全局 +1pp 左右。
- 这些收益有重叠，再乘“能到达终局步的比例” q≈0.6，合计约 **+5~6pp**；保守取 **+3~5pp**。

可证伪点：

- T27（叠碗）/T10（插排）调试槽的终局成功率提升 **<5pp** → SPM/MDR 假设不成立，退回 SSG+SVL。
- 地图谓词 F1 **<0.85** → 地图不可用于步骤验证，只保留槽位/锚点。
- 地图线程 p99 **>100ms** 或拖慢策略 → 关掉检测器/降频，退回 2D 锚点。
- 非地图任务出现回归 → 说明地图噪声大于收益，回滚。

### 2.4 为什么这比“再训一个更大的 VLA/世界模型”更划算

- 头部模型 4B/14B 已经把“从图像到动作”的域内能力拉得很高；UniBot 的 30% 更像是**场景/状态/本体迁移**问题，不是参数不够。
- 14B world model 的推理 7Hz、150ms/chunk；再叠一个 14B 做闭环，延迟和算力都不划算。S3M 用 CPU/小 GPU 就能跑 2–5Hz，且可解释。
- S3M 不改变基座权重，不引入“多模型按任务切换”的合规风险；它把“状态”从模型里拿出来，反而让单模型审计更容易。

## 3. S3M 的轮廓

```text
language（160 条复述之一）
      │
      ▼
SSG 编译器：task_id → K 个评分步骤 → 谓词模板 + 权重 w_k
      │
obs（4 RGB + EE base + waist）─► S3M 建图线程
      │    ├─ 头部双目/单目 + 桌面平面 → base 系 2.5D 点
      │    ├─ open-vocab 检测/分割 → 对象节点 V
      │    ├─ 跟踪/关联 → 位姿 T_B^i、置信度、状态
      │    └─ 关系边 E：on / in / left-of / stacked / holding / closed
      │
      ├─► 步骤验证：pred_k(G) → done/regressed → s_t
      ├─► 槽位图：容器局部占据 + 语义槽位 + OPT 先验 → 目标位姿
      ├─► 地图差分：ΔG → 外部移动/撤销/遮挡 → 回退步骤 + 修复
      └─► MKT：图键 + 相位 → K 条演示上下文（可选）
      │
      ▼
GPR-VLA（唯一 checkpoint）：语言 + 四视图 + 锚点 + 可选图 token → action chunk
      │
      ▼
SVL：接近 → 缓放 → 谓词/稳定校验 → nudge / regrasp / retry（≤2 次）
      │
      ▼
NRB/MDR：human 备注剧本 → 恢复对；L2L：实验室背景/位置数据
```

一句话：**SSG 给“评分骨架”，S3M 给“当前世界状态”，SPM 给“放哪”，MDR 给“被改了怎么办”，GPR-VLA 给“怎么动”。**

## 4. 风险与合规（先立后破）

- **单模型边界**：S3M 本身是确定性代码 + 数据；但 open-vocab 检测器/分割器是额外学习组件。合规开关 `perception_stack = classical | openvocab`：默认 classical（颜色/背景/几何/双目），只有邮件确认“辅助感知不算第二任务模型”后才开 openvocab。无论哪种，模型卡写清“一个策略 checkpoint + 确定性地图/工具”。
- **无深度/无标定**：`head_stereo_left/right` 是否已标定需验证；若否，用单目深度 + 桌面平面尺度，或退化到 2D 单应。地图失败不能阻塞策略，必须有“无图模式”。
- **遮挡/透明/布料**：T14 药瓶、T19 拉链、T16 毛巾、T32 注射器这类任务，S3M 只做粗位姿/阶段，不承诺精细谓词；谓词置信度低时交回 VLA/学习谓词头。
- **人为干扰漏检**：人手遮挡、快速移动、出视野都可能漏；MDR 只处理“确认的外部图变更”，不处理“猜测”；不确定时保守重试当前步。
- **延迟**：地图线程与策略线程共享 GPU；必须限流、缓存、降级。`get_action` 的 p99 是硬指标，地图不能拖垮它。
- **reset/静态层**：`reset()` 必须清动态层；静态层只在场景指纹匹配时复用；否则重建。不能假设评测场景跨 episode 不变。
- **统计噪声**：单任务调试只有 10 次，终局成功率 SE≈14.5pp；不能只看 10 次成败，必须看步骤级/地图 F1/恢复成功率，并尽量多预约几个调试槽。
- **安全**：human 在 workspace 内时，策略应暂停/后退，不能抓人手；MDR 的“等待”优先于“抢动作”。

## 5. 一句话押注

**把语义地图做成评分步骤的状态总线（S3M）：用对象图谓词防假完成、用地图差分恢复人为干扰/undo、用容器槽位占据图选放置点；这是当前最值得押注的创新点。**

## 2. 评分算术：为什么 S3M 要先保 success

### 2.1 排名公式

```text
avg_success = (1/32) Σ_t (1/10) Σ_j 1[task t, trial j 所有步骤完成]
avg_step    = (1/32) Σ_t (1/10) Σ_j (1/100) Σ_k w_k 1[step k 完成]

rank = lexicographic(avg_success, avg_step, -submission_time)
```

所以：

- **终局步骤是 success 的闸门**：任何一步没完成，success=0；但 step 仍可能很高。
- **步骤分只在 success 打平时决定名次**。如果为了多拿 10 分步骤分而把 success 从 0.30 降到 0.29，排名会下降。
- 对 S3M 的决策规则：**先判断“这一步是否必须做/是否已经完成”，再判断“能不能多拿部分分”**；不确定时选 success 概率更高的保守动作。

### 2.2 终局放置仍是最大杠杆

- 32 个终局步骤里 28 个是放置/插入/堆叠/闭合类；终局权重合计约 39.8%（前轮抓取 32 个 info.json 统计）。
- 终局步骤跨全部 5 轴：位置、干扰物、背景、未见物品、人为干扰下都要做最后一下。
- 但注意：**success 优先意味着“终局放置成功”比“终局步骤部分分”更重要**；S3M 的 SVL 应该先保证“真的放稳/插到位”，而不是“多做一个摆正动作”。

### 2.3 跨轴杠杆

| 改进 | 作用范围 | 全局增益近似 |
|---|---|---|
| 单轴成功率 +Δ | 1/5 权重 | 0.2Δ |
| 终局放置成功率 +Δ | 所有轴×所有任务 | ≈ Δ×q（q≈0.5–0.7） |
| 人为干扰恢复 +Δ | 20% trials（2/10） | 0.2Δ |
| 放置槽位 +Δ | 约 60% 任务 | 0.6Δ |

终局放置仍是约 2.5–3.5× 于单轴改造的杠杆；MDR 的直接杠杆是 0.2Δ，但因为 human 子集基线低、恢复成功率高，实际增益可能更集中。

### 2.4 时间预算

- 演示中位数约 6–10s/任务；官方 180s。
- S3M 的地图建档 1–2s、每次恢复 1–3s、SPM 候选评估 <50ms；普通任务允许 1–2 次恢复，长程任务（T16/T17/T31）最多 1 次。
- 如果地图线程拖慢策略，优先降地图频率，不降策略频率。

### 2.5 统计功效

- 320 trial、p≈0.30：单臂 SE≈2.56pp；配对/分层可降到 ~1.5pp。+3pp 才有可检测性，+5pp 更稳。
- 单任务调试 10 次：SE≈14.5pp；**不能只看 10 次终局成败**。必须看步骤级成功率、地图 F1、恢复成功率，并尽量多预约几个调试槽/任务。
- 消融用 paired bootstrap；报告 95% CI；CI 跨 0 不上线。

## 3. S3M 形式化

### 3.1 表示

```text
任务 τ：语言 → task_id（32×5=160 条复述匹配）
步骤 k=1..K_τ，权重 w_k，Σw_k=100
谓词 φ_k(G)，期望后置图 G_k^post
状态 s_t = (k, done[1..K], regressed, recovery_budget)

图 G_t = (V_t, E_t, U_t)
V_t: 对象节点 v_i = (id, class, role, T_B^i, extent, conf, state)
     role ∈ {target, receptacle, tool, distractor, human_hand, unknown}
     T_B^i = (x,y,z,θ) 或 SE(3)；桌面任务主要用 2.5D
     state ∈ {free, grasped, placed, occluded, moved, removed}
E_t: 关系边 (i,j,r,c)
     r ∈ {on_top, in, left_of, right_of, front_of, stacked_on,
          holding, closed, open, inserted, occupied}
U_t: 每个节点/边的置信度、可见性、最后观测时间
```

任务 schema 由 `score_steps` 编译，不由模型自由生成。每类任务只需要少数谓词：

| 任务族 | 例子 | 关键谓词 |
|---|---|---|
| pick-place | T01/T02/T04/T08/T21/T25 | `holding` → `in/on_top`；颜色/位置匹配 |
| stack | T20/T27 | `on_top` + `stacked` + 稳定性 |
| insert | T10/T26/T32 | `aligned` + `inserted` + 深度/方向 |
| open/close | T09/T14/T17/T18/T19/T23/T28/T29/T31 | `open/closed` + 铰链/拉链/盖子 |
| sort/arrange | T04/T06/T15/T21/T22/T24 | `left_of/right_of` + 类别/颜色序 |
| unlock | T12 | 钥匙旋转 + 锁环翻转 |
| deformable | T16/T19/T23 | 粗位姿 + 阶段（不承诺精细几何） |

### 3.2 SSG 编译器

输入：`info.json` 的 `score_steps`（中英）+ 5 条英文复述 + 任务描述；输出：`K_τ` 个谓词模板。做法：

1. 32 个任务手工/半自动编译（LLM 生成候选，人工校验 32 个；这是一次性离线工作，不进推理）。
2. 指令匹配：160 条复述的规范化精确匹配（小写、去标点、数字归一）+ 句向量兜底；匹配到 task_id 后用 schema，不需要在线 LLM。
3. 每个步骤给一个 `predicate` 或 `predicate_set`；无法几何化的（拉链、倒药、注射）标 `learned_or_vla`，不强行做。
4. 权重 `w_k` 只用于诊断和重试预算，不用于“为了部分分牺牲 success”。

### 3.3 在线建图

```python
def update_map(obs, schema, prev):
    # 1) 相机位姿（base 系）
    T_B_T = fk_waist(obs.lower_body[-3:])          # yaw/roll/pitch
    T_B_C = T_B_T @ T_T_C_head                     # 固定头架，离线标定/URDF
    # 2) 深度：双目优先，单目+桌面尺度兜底
    depth = stereo(obs.head_left, obs.head_right)  # 或 monocular_depth()
    pts_B = backproject(depth, T_B_C, K_head, obs.head_left)
    plane = ransac_plane(pts_B)                    # 桌面支撑面
    # 3) 检测/分割（open-vocab 可选）
    dets = detect(obs.head_left, schema.roles)     # 或 classical color/geometry
    # 4) 关联/跟踪
    tracks = associate(prev.tracks, dets, pts_B, plane)
    # 5) 位姿/关系
    for tr in tracks:
        tr.pose = fit_pose_2p5d(tr.mask, pts_B, plane)
        tr.conf = confidence(tr)
    E = infer_relations(tracks, plane)             # on/in/left-of/stacked/holding
    # 6) 人/手：单独节点，用于外部干扰归因
    hands = detect_hands(obs)
    return Graph(tracks, E, hands, T_B_C, plane)
```

关键工程点：

- **相机位姿**：`state_d435`/`state_torso` 在数据集里可用于离线验证 FK；API 只给 waist，在线用 FK。若 FK 与桌面平面残差大，退化到“桌面单应 + 2D 锚点”。
- **双目**：`head_stereo_left/right` 若是已标定双目，SGBM/RAFT-Stereo 均可；若视差质量差，用单目深度（Depth Anything 3/VGGT 类）但只取相对深度，用桌面平面/已知相机高度定尺度。
- **2.5D**：物体用“平面中心 + 朝向 + 高度/支撑面”表示；堆叠时用支撑物体的顶面 z，不重建完整网格。
- **关联**：3D 距离 + mask IoU + 类别 + 运动预测（卡尔曼）；人手遮挡时保留 last_seen，不立刻删节点。
- **关系**：`on_top` 用水平重叠 + z 差；`in` 用容器开口多边形 + z 范围；`left_of` 用桌面坐标系排序；`holding` 用 EE 距离 + 夹爪开度 + 物体随动。

### 3.4 谓词定义与置信度

| 谓词 | 几何判据 | 置信度/兜底 |
|---|---|---|
| `on_top(a,b)` | `||πxy(c_a)-πxy(c_b)|| < r_b`；`|z_a-(z_b+h_b)| < ε_z`；支撑多边形包含 | 检测/位姿置信度乘积；低置信度用腕部近景 |
| `in(a,b)` | `πxy(c_a)` 在容器开口内；`z_a` 在底/沿之间 | 透明容器用边缘/深度；失败交 VLA |
| `stacked(a,b)` | `on_top` + 倾角 `<θ_max` + 0.3s 稳定 | 叠碗/杯；滑落则回退 |
| `left_of(a,b)` | 桌面系 `x_a < x_b - margin`；支持 leftmost/middle/rightmost 排序 | 颜色/类别序由 schema 给 |
| `holding(g,a)` | `||T_B^g-T_B^a||<ε` + 夹爪开度≈物宽 + 随动 | 夹爪开度是强信号 |
| `closed(lid)` | 盖子相对容器位姿 + 缝隙/角度 | 拉链/软包用学习谓词头或 VLA |
| `inserted(plug,socket)` | 轴向距离 + 角度 + 插入深度（腕部视觉） | 力/接触不可得；用视觉+电流（若有） |
| `poured(bottle,cup)` | 瓶倾斜角 + 杯内液面/内容（视觉） | 透明/液体难；交 VLA |

置信度与迟滞：

```text
set done[k]   if φ_k > θ_on  for d_on frames   (θ_on≈0.7, d_on≈3)
clear done[k] if φ_k < θ_off for d_off frames  (θ_off≈0.4, d_off≈5)
```

不允许仅凭 VLA 的“完成”置信度推进；VLA 只作为低置信度时的第二意见。

### 3.5 步骤验证与假完成防护

```python
def verify_step(k, G, s):
    c = phi[k](G)
    if not s.done[k] and c > TH_ON:
        s.done[k] = True
        s.k = k + 1
    elif s.done[k] and c < TH_OFF:
        affected = earliest_affected_step(G, s)
        if affected is not None:
            s.done[affected:] = False
            s.k = affected
            s.regressed = True
    # final guard: 最后一步必须稳定 0.5s，且没有 regression
    if s.k == K and not stable(G, phi[K], 0.5):
        s.done[K] = False
    return s
```

- **防跳步**：步骤只能顺序推进；不能因为“看起来像完成了”跳过前置。
- **防假完成**：最后一步 + 全步骤 done 后，再等 0.5s 稳定；如果物体掉落/滑动/被人拿走，回退。
- **防“为了步骤分多动作”**：如果当前步骤已完成且剩余时间不足以安全重试，直接进入下一步；不为了美观做额外摆正。

### 3.6 MDR：地图差分恢复

```python
def map_diff_recovery(G_prev, G_now, s, budget):
    edits = graph_edit(G_prev, G_now)          # moved/removed/added/occluded
    for e in edits:
        if e.object is None or e.object.role == "distractor":
            continue
        if is_robot_caused(e, G_now):          # held/contact/gripper
            continue
        if e.type in ("moved", "removed"):
            k = earliest_affected_step(e.object, s)
            if k is None: continue
            s.done[k:] = False
            s.k = k
            if budget <= 0: return s, "no_budget"
            return s, repair(e, G_now, k)
        if e.type == "occluded":
            request_reobserve(e.object)          # 腕部/waist 小幅扫描
    return s, None
```

外部/机器人归因：

- 物体与夹爪距离近、夹爪闭合、物体随 EE 动 → robot-caused。
- 物体在非夹爪侧移动、人手节点靠近、运动方向与人手一致 → external。
- 遮挡/不确定 → 不猜测；请求再观测或保守重试当前步。

修复库：

| 编辑 | 修复 |
|---|---|
| 目标物体被平移 | 重定位 → 重新抓取 → 重放当前步 |
| 容器被平移 | 更新容器系 → 重算槽位 → 继续 |
| 已完成步骤被 undo（碗被拿走/拉链被拉开/盖子被拧回） | 回退到该步 → 重做 |
| 目标被拿走 | 若还能看到 → 追；若不在 workspace → 标记不可恢复，保守继续/失败 |
| 人手在 workspace | 暂停 0.5–1s，后退，等手离开；不抢动作 |
| 快速运动目标（传送带） | 用速度预测 + 提前量；重新抓取 |

预算：普通任务 ≤2 次，长程 ≤1 次；每次恢复前检查剩余时间；恢复失败则回退到“重试当前步”，不无限循环。

### 3.7 SPM：容器局部槽位图

对每个 receptacle（盘子/架子/盒子/杯架/碗）：

```text
F_c: 容器局部系（原点=开口/支撑面中心，z=法向）
O_c: 占据栅格（1–2cm），记录 occupied/free/support/height
S_c: 语义槽位标签（leftmost/middle/rightmost、颜色匹配、stack_top、inside）
```

候选评分：

```text
score(p) = λ1 * demo_prior(p)          # OPT：K 条演示的容器系释放位姿 KDE
         + λ2 * free_space(p)          # 占据图 + 间距
         + λ3 * semantic_match(p)      # 颜色/顺序/类别
         + λ4 * reachability(p)        # IK/EE 可达、避碰
         - λ5 * collision_risk(p)      # 与容器壁/其他物体/人手
```

执行：

1. 选 top-1 候选，投影到头部/腕部图像，渲染十字 + 朝向 + 容差圈。
2. 接近 → 慢放 → 松爪 → 0.5s 稳定 → 谓词校验。
3. 失败则 top-2，最多 2 次；仍失败则重抓/重定位。

叠放特殊规则：

- `z_target = z_support_top + h_object/2`；朝向与支撑物体对齐；倾角阈值。
- 如果支撑物体被移动（MDR），槽位图立即失效，重算。

插入特殊规则：

- 目标不是“点”而是“轴向位姿”：`(socket_frame, approach_dir, depth)`；先对准，再沿轴插入；腕部视觉/电流（若可得）确认。
- 透明插排/网口：用边缘/深度 + 学习谓词；地图只给粗定位。

### 3.8 SES：场景建档与自校准

```python
def reset_scene(obs):
    clear_dynamic_layer()
    fp = scene_fingerprint(obs)     # 桌面平面系数 + 静态物位姿 + 相机位姿
    if static_layer and match(fp, static_layer.fp, tol):
        reuse_static_layer()
    else:
        static_layer = build_static_layer(obs)   # 桌面/架子/固定容器
    scan_workspace(obs)              # 1–2s：head/waist 小幅扫描
    return build_dynamic_layer(obs)
```

- **自校准**：桌面平面 RANSAC；头部相机位姿 = waist FK × 固定头架；用平面残差/重投影误差验收。若残差大，退化到 2D 单应。
- **静态/动态**：静态层只含桌面、架子、固定容器；动态层含任务物体。`reset()` 必须清动态层；静态层只在指纹匹配时复用。
- **多机器人**：每个端口独立动态图；静态标定可按端口/机器人缓存，但必须在线验收。
- **场景落地**：同一套 S3M 跨 32 任务；只换 schema，不换模型；新实验室只需采背景/位置数据，不需要重训。

| 模块 | 频率 | 预算 | 降级 |

| 双目/单目深度 | 5–10Hz | 10–30ms | 只用桌面单应 |

## 4. 与 GPR-VLA 的集成

### 4.1 最小可行版（MVP，不重训）

- GPR-VLA 保持原 checkpoint；S3M 只做三件事：给锚点、给步骤状态、给恢复信号。
- 观测侧：把 SPM 选中的 6D 目标投影成头/腕图像上的十字 + 容差圈；训练时用演示真实目标做同样渲染（同分布 overlay）。
- 动作侧：策略仍输出 action chunk；S3M 在 chunk 间验证，不插手中低频动作。
- 恢复侧：MDR 触发时，重置 `done`/`k`，把“重做第 k 步”作为内部上下文（文本/标志），策略重新生成 chunk。
- 合规：S3M 是确定性代码 + 数据；检测器是可替换工具；模型卡写清。

### 4.2 M2P：图 token（研究扩展）

- 图编码器：2 层 GNN/Transformer，节点特征 = 类别嵌入 + 相对位姿 + 状态 + 置信度；边特征 = 关系类型 + 距离。
- 输出 32–64 个 map tokens，经 cross-attention 注入 VLA 的 action expert（不是 VLM 主干，避免破坏语言先验）。
- 训练：在演示上同步构建 S3M，随机 dropout 图（防止模型只会读完美图）；损失 = 原 flow loss + λ_map * 动作一致性 + λ_pred * 谓词 BCE。
- 资源：6B LoRA + 图编码器；8×H100 1–2 周；风险是过拟合/延迟；不作为 MVP。

### 4.3 MKT：图键检索（ICR 的降级版）

- 键：任务嵌入 + 步骤相位 + 关系直方图 + 目标/容器相对位姿 + 最近 1s EE 运动。
- 值：演示段缓存编码 + 动作先验（K=3–4）。
- 检索：HNSW，<5ms；缓存离线编码；K 小，延迟可控。
- 注入：上下文 token + 动作先验小权重融合；训练时同步注入，避免推理期首次见到。
- 失败回退：透明/布料任务键不稳 → 只用相位/动作先验，不做位姿迁移。

### 4.4 训练课程（若做 M2P/谓词头）

| 阶段 | 数据 | 目标 | 退出条件 |
|---|---|---|---|
| 0 | 真实 100% | 复现 GPR-VLA 基线 | held-out 不降 |
| 1 | +S3M 自动标签 | 谓词头 F1 | F1 >0.85 |
| 2 | +SPM 锚点渲染 | 锚点跟随 | 离线误差 −10% |
| 3 | +MKT 上下文 | 检索增益 | 终局段误差 −10% |
| 4 | +MDR 恢复对 | 撤销恢复 | 恢复成功率 >50% |
| 5 | +M2P 图 token | 端到端增益 | 真机 +5pp，无回归 |
| 6 | 量化/蒸馏 | p99 | <100ms |

### 4.5 损失（仅训练阶段）

```text
L = L_flow + λ1 L_pred + λ2 L_map + λ3 L_rec + λ4 L_reg
```

- `L_pred`：步骤谓词 BCE/焦点损失（S3M 自动标签）。
- `L_map`：M2P token 与动作的一致性（仅 M2P）。
- `L_rec`：恢复段动作（NRB 对）。
- `L_reg`：回归/回退监督（图差分标签）。
- MVP 全部 λ=0；不引入新学习组件。

## 5. 数据引擎

### 5.1 S3M 自动标注

- 回放 33k 演示：用真实 `state_d435`/`state_torso` 校准 FK；构建每帧对象图；用夹爪事件/物体轨迹切步骤；产 `(task, step, object, relation, pose, confidence)`。
- 人工抽检 10%；谓词 F1 <0.85 的类别不进训练。
- 输出：谓词头训练集、步骤边界、容器系释放位姿、失败/重试片段。

### 5.2 NRB：官方备注恢复对

- 用 human_1/human_4 备注构造图编辑：移动/移除/undo；从演示中找“被破坏前”和“恢复后”片段。
- 生成恢复对：`(G_broken, step k, repair action)`；训练 MDR 的修复策略/谓词回退。
- 即使备注不是评测真实剧本，也是分布内高价值扰动。

### 5.3 OPT：容器系释放位姿

- 每条演示：释放时刻 EE 位姿 `T_B^G(t_rel)`；容器系 `T_B^R`；`H_i=(T_B^R)^{-1}T_B^G`。
- 线上：K 条行为对齐演示；`median xyz` + 四元数弦均值；`σ` 驱动控制风格。
- `τ_task` 从演示分布 95 分位估；用于谓词阈值/放置容差。

### 5.4 L2L：实验室数据协议

- 3 实验室 × 2 任务 × 100–200 条；四路相机、EE base/torso、lower_body 同 schema；每任务 5 条复述 + 步骤标签。
- 只采刚体/容器类放置段；布料/拉链/透明第一轮不碰。
- QA：同步、时长、平滑、夹爪事件、步骤覆盖；拒绝率 >20% 停采。
- 合规：外部数据默认 OFF；邮件确认后 ON；许可/署名写清。

### 5.5 合成数据（窄）

- 只用于 S3M 谓词/检测/槽位：桌面场景、刚体、容器、背景/位置扰动；不做 full physics。
- 合成不主导：<30% 训练样本；用 GF 软权重。

### 5.6 QA

- 自动：四路同步、帧率、动作平滑、夹爪闭合、步骤覆盖、复述匹配。
- 人工：10% 抽检；谓词/位姿误差 >阈值退回。
- 版本化：每批数据带 schema 版本、标定版本、代码 commit。

## 6. 部署与接口工程（场景落地）

### 6.1 N 端口与异步

```text
端口 8765..8765+N-1：每端口一个 PolicyService
  ├─ 策略线程：get_action（读缓存，p99<100ms）
  ├─ 地图线程：2–5Hz（检测/深度/图更新）
  └─ 恢复线程：事件驱动（MDR/SVL）
共享：只读静态标定/模型权重；不共享动态图/历史
```

- 每端口 `reset()` 清动态图、步骤状态、恢复预算；静态层按指纹复用。
- 健康检查：端口存活、模型 warmup、地图线程心跳；异常时降级到“无图模式”。
- 日志：每步 `k/done/φ/恢复/延迟`；便于赛后复盘与模型卡。

### 6.2 标定

- 离线：用数据集 `state_d435`/`state_torso` 拟合 `T_T_C_head`；验证重投影 <5px、桌面 <5mm。
- 在线：waist FK + 桌面 RANSAC；残差大 → 2D 单应。
- 双目：验证 baseline/intrinsics；视差质量差 → 单目 + 桌面尺度。
- 多机器人：每端口在线验收；不假设完全一致。

### 6.3 退化路径

| 失败 | 退化 |
|---|---|
| 无深度/视差差 | 桌面单应 + 2D 锚点 + 高度先验 |
| 检测器漏检 | 颜色/边缘/背景差分；腕部近景 |
| 图谓词低置信 | 只用槽位/锚点；步骤推进交 VLA + 事件 |
| 地图线程超时 | 用上一帧图；跳过本帧；不阻塞策略 |
| 人手遮挡 | 暂停/后退；等待；不抓人手 |
| 静态层不匹配 | 重建；不硬套 |

### 6.4 模型卡/合规

- 一个策略 checkpoint（GPR-VLA/WLA 底座）；S3M/SSG/SPM/MDR 是确定性代码；MKT/NRB 是数据；检测器是工具。
- 写清：外部数据开关、检索库来源、标定版本、延迟、失败模式。
- 单模型审计：如果官方认定检测器算第二模型，切 `perception_stack=classical` 或把检测头并入 checkpoint；提前邮件确认。

### 6.5 延迟预算

| 项 | 目标 |
|---|---|
| `get_action` p99 | <100ms |
| 地图线程单帧 | <80ms（检测+深度+图） |
| 地图更新频率 | 2–5Hz |
| SPM 候选评分 | <50ms |
| MDR 决策 | <10ms |
| 恢复动作 | 1–3s/次，≤2 次 |

## 7. 实验设计

### 7.1 离线

| 实验 | 数据 | 指标 | 通过线 |
|---|---|---|---|
| 地图位姿 | 32 任务 × 50 演示 | 物体中心误差、朝向误差 | <1cm / <5°（刚体） |
| 谓词 | 同上 + 人工抽检 | F1、召回、误报 | F1 >0.85 |

| 延迟 | 单卡/多端口 | p50/p99 | p99 <100ms |

### 7.2 真机调试槽

优先任务：

1. **T27 StackBowls**：叠放/undo/槽位，最直接验证 SPM+MDR。
2. **T10 PlugCharger**：插入/对准/拔出重插，验证轴向位姿。
3. **T19 ZipUp**：闭合/拉开，验证非几何谓词的回退。
4. **T24 ConveyorSorting**：运动目标/重新抓取。
5. **T12 Unlock**：对象被移动/拿走。

每个任务 10 次（官方单任务通道），但**不只看终局**：记录每步谓词、恢复次数、地图 F1、延迟。若允许，重复预约 2–3 个槽位，把 n 提到 20–30。

### 7.3 指标

- 主：terminal success、step success、false completion rate。
- 次：恢复成功率、干预率、地图 F1、槽位 top-3、p99、平均时长。
- 安全：人手距离、碰撞/急停次数。

### 7.4 实验矩阵

| ID | 配置 | 验证 |
|---|---|---|
| E0 | GPR-VLA 基线 | 复现 |
| E1 | +S3M 谓词/步骤状态 | 假完成/跳步下降 |
| E2 | E1+SPM | 放置成功率/槽位 |
| E3 | E2+MDR | human/undo 恢复 |
| E4 | E3+SES | 换场景/重置稳定性 |
| E5 | E4+MKT | 上下文增益/延迟 |
| E6 | E5+M2P | 端到端（研究） |
| E7 | 全量+量化 | 部署 |

消融：地图 on/off；双目 vs 单目 vs 2D；检测器 vs oracle；静态层 on/off；K∈{1,2,4}；迟滞阈值；恢复预算 0/1/2；SPM vs 纯锚点。

### 7.5 统计

- 320 trial，SE≈2.6pp；配对 bootstrap；报告 95% CI。
- 调试槽 10 次，SE≈14.5pp；用步骤级/恢复率/F1 作为主证据，终局成败只作方向。
- 多个任务/多次预约合并；不要用单次 10 trial 的 +10pp 宣称成功。

### 7.6 Go/No-Go

- Go：T27/T10 终局 +5pp；恢复 >50%；F1 >0.85；p99 <100ms；无回归。
- No-Go：任一硬指标失败 → 回退到 SSG+SVL；地图只保留槽位/锚点。

### 8.2 主线 I1：S3M 评分步骤语义地图

- **动机**：UniBot 的成功=所有步骤完成；头部 VLA 没有持久对象/步骤状态；human 干扰会 undo；step score 只在打平时有用。需要一个“做到哪、东西在哪、谓词成不成立、有没有被改”的状态层。
- **与现有方案差异**：通用 scene graph 服务导航/规划；S3M 的 schema 由公开 score_steps 编译，只跟踪任务相关对象，输出步骤谓词/回退，不做 planner。FOUND-IT 做 task-driven granularity，但不做评分步骤；OCC4M 做对象记忆，但不做步骤回退；MomaGraph 做任务图，但不做在线执行验证。S3M 把三者接起来。
- **技术可行性**：4 RGB + waist FK + 双目/单目 + 桌面平面；2.5D 图；检测器可换；确定性代码；不重训。离线用数据集 `state_d435`/`state_torso` 验证。
- **资源**：1–2 名工程师 × 2–3 周；1 张 24GB GPU 做检测/深度；33k 回放 CPU/GPU；标注抽检 10%。
- **落地步骤**：① 编译 32 任务 schema；② 离线回放/标定；③ 建图器/跟踪；④ 谓词/迟滞；⑤ 状态机/假完成；⑥ 调试槽 T27/T10；⑦ 全量接入。
- **风险**：无深度/标定；检测/遮挡；透明/布料；单模型边界；延迟；reset。缓解：2.5D/退化/合规开关/异步/动态层。

### 8.3 主线 I2：SPM 容器槽位图

- **动机**：放置/插入/堆叠类约占 60% 步骤；现有 anchor 只给“点”，不给“哪个槽、有没有占、会不会撞、顺序对不对”。
- **差异**：容器局部占据图 + 语义槽位（leftmost/middle/rightmost、颜色匹配、stack_top、inside）+ OPT 位姿先验 + 可达性/碰撞；不是单点 anchor，也不是纯语言坐标。
- **可行性**：容器系可由检测/边缘/已知几何估计；占据图用 2.5D；OPT 用数据集 EE 位姿；渲染/投影确定性。
- **资源**：OPT 库（8×H100 数天）；1 人 × 1–2 周；调试槽 T27/T10。
- **步骤**：容器系→占据→槽位标签→评分→渲染→执行→谓词验证→失败换槽。
- **风险**：透明容器/堆叠遮挡/槽位歧义；缓解：腕部近景、多候选、top-3、回退 anchor。

### 8.4 主线 I3：MDR 地图差分恢复

- **动机**：human 占 20%，官方备注明确是“移动/undo”；没有显式状态就无法知道哪一步被破坏。
- **差异**：不是只做变化检测（FOUND-IT++），而是把图编辑映射到评分步骤回退，并调用修复库；不是重训一个恢复策略。
- **可行性**：跟踪/谓词已有；修复库是少量原语；human 备注可回放；零梯度。
- **资源**：1 人 × 1–2 周；human 备注/合成脚本；调试槽 T27/T19/T12。
- **步骤**：图 diff→机器人/外部归因→最早受影响步骤→回退→修复→预算→安全。
- **风险**：人手遮挡/快速移动/出视野/误报；缓解：不确定不猜、再观测、保守重试、暂停。

### 8.5 主线 I4：SES 场景建档/自校准

- **动机**：多机器人/多场景/reset；不能每场景重训；深度/标定 API 不给。
- **差异**：waist FK + 桌面平面 + 场景指纹；静态/动态分层；不是 full SLAM。
- **可行性**：URDF/数据集可验证；2.5D；失败退 2D。
- **资源**：1 人 × 1 周；标定数据；调试槽。
- **步骤**：FK→平面→指纹→静态层→reset→QA。
- **风险**：头架差异/静态层过期/reset 规则；缓解：在线验收、默认动态、指纹不匹配重建。

### 8.6 研究扩展 I5/I6

- **I5 MKT**：动机是 33k 少样本库；键=S3M 图/相位/相对位姿；K=3–4；缓存；训练时注入。资源 1–2 周/1 GPU。风险：透明任务键失效/延迟。状态：升级 ICR，但非主线。
- **I6 M2P**：动机是让 VLA 直接读图状态；图编码器+cross-attn+map dropout；6B LoRA/8×H100/2–3 周。风险：过拟合/延迟/单模型审计。状态：研究扩展，MVP 不做。

### 8.7 保留/升级/降级/砍

- **保留**：I7 SSG、I8 OPT、I9 NRB、I10 L2L、I11 DebugLoop、I12 GPR-VLA。
- **升级**：I13 TLE 自动标注；I5 MKT（ICR 降级）。
- **降级**：I14 TCLB/FLEET；跨 episode 静态图默认关；步骤分降为 tie-break。
- **砍**：通用 3D SLAM/全场景高保真重建；全 32 任务孪生；自由仿真数据；运行时 MPC；仿真 RL；布料/拉链/透明全物理；WMA-0 进主路径；每任务 LoRA/模型合并。
