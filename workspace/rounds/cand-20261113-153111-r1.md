# 第 68 轮（承接第 67 轮「SimRAS 仿真增强闭环」IP-233~242；灵感循环第 4 轮；本轮灵感：「用户需求分析」×「模型量化」）

> 第 67 轮 SimRAS 把 RAS 升级为「离线仿真预训练 + 在线世界模型推理 + 视觉问答审计」三层结构，解决了「未来风险怎么演化、怎么可解释地审计」。但它悄悄默认了三个**以模型为中心**的前提：(1) 风险阈值 `R_max` 是普适的，与具体用户无关；(2) 算力/能耗是充足的，WM 与 VQA 可以常驻；(3) 解释深度是固定的。真实部署中这三条全都不成立——**用户需求是异构且可变的，而嵌入式平台的计算/精度预算迫使整条链路做混合精度量化**。
>
> 本轮的核心命题是：
>
> **把「以模型为中心的安全闭环」升级为「以需求为契约的量化闭环」：把用户需求显式化为一份可验证的「安全-性能契约」`C_user`，把混合精度量化配置 `b` 当作履约成本（契约的对偶变量），并由「量化感知证书」证明量化后的闭环仍满足该契约。记作 NCQ（Needs-Contract Quantization：需求契约量化）。**
>
> NCQ 问的不再是「模型预测得多准」，而是「**这份精度，是否恰好买到了这位用户真正想要的安全、速度、隐私与解释**」。它把 SimRAS 的「模型→风险→证书」链条，翻转为「需求→契约→量化→证书」的履约链条。

## 0. 直觉与动机

**灵感 1（用户需求分析 → 安全不是标量，而是一份契约）**
直觉：第 67 轮把安全压缩成一个标量 `λ_risk`，仿佛所有用户共享同一套风险偏好。但真实用户是异构的：老人要「慢而稳」，产线要「快而准」，隐私敏感者要「本地不上云」，新手要「解释清楚」。把需求压成单一阈值，等于系统替用户做了价值判断。更合理的做法是把需求**显式化**为一份可验证的契约 `C_user = (R_max, L_max, E_min, P_min, h_max)`，让系统去「履约」而不是「猜测」。这把不可见的偏好变成可审计、可争辩、可重签的对象。

**灵感 2（模型量化 → 比特就是履约成本）**
直觉：契约不是免费的。世界模型、VQA、情绪分类器要常驻嵌入式平台，就必须量化。但量化绝非纯工程细节——它直接改变风险估计：4-bit 情绪头误判率上升，8-bit WM 的滚动误差变大，量化误差还会跨头相关。因此「用多少比特」本质上是「为了满足这份契约，愿意付多少算力/精度」。**量化配置 `b` 是契约的对偶变量**：契约越严，比特越高；比特越低，成本越小但需要更厚的安全裕度补偿。

**灵感 3（两灵感合流 → 需求-量化-证书三角）**
直觉：需求给约束，量化给成本，证书给保证。三者构成一个稳定的三角：
- **需求**：`C_user` 定义可行域；
- **量化**：`b*` 在可行域内最小化延迟/能耗；
- **证书**：`J_NCQ` 证明「量化后的闭环仍落在契约内」，并显式携带量化误差补偿 `margin_comp`。
这把 SimRAS 的「模型中心」翻转为「需求中心」：不是「我们能做到多安全」，而是「你要求多安全，我们用最便宜的方式兑现」。

**灵感 4（需求漂移 → 契约是会过期的）**
直觉：用户会疲劳、换任务、改主意。第 67 轮的 `λ_risk` 先验一旦固化就会过期。NCQ 必须检测需求漂移并**重签契约**，且用迟滞（hysteresis）避免频繁抖动——否则系统会在两套契约间反复横跳，产生控制突变。这是「需求分析」从一次性问卷升级为**持续协商**的关键。

**灵感 5（解释即需求 → VQA 的比特预算由用户定）**
直觉：`E_min`（最低解释深度）直接决定 VQA 是端上跑还是卸载到 edge/cloud。这让「量化」与「可解释性」第一次显式耦合：想省钱就低比特端上跑，想解释清楚就得付更高的比特或通信代价。隐私级别 `P_min` 同理——若要求本地，面部 embedding 绝不能出设备，`b_ERG` 的下界由本地误判约束给出。

**灵感 6（合流 → NCQ 六层结构）**
NCQ 复用 SimRAS 的时序骨架，换装为：
1. **NPE Needs Preference Elicitor**：成对偏好查询 + 贝叶斯后验，抽取用户需求；
2. **CB Contract Builder**：把后验压成可验证契约 `C_user`（lexicographic 优先级）；
3. **QSim Quantization-aware Sim Calibration**：用 SimEngine 在 `D_sim` 上为每个候选 `b` 标定量化误差、风险 CDF、延迟；
4. **QAlloc Quantization Allocator**：在 `sat(b,C)` 约束下求最小成本比特分配；
5. **QRAS Quantized Runtime**：量化版 ERG/EFS/C-RAS/ERS + WM，安全裕度用 `ρ_safe^q`；
6. **QCert + CG + RC**：量化感知证书、契约守护、需求漂移重签。

## 1. 形式化定义（增量：定义 276–295）

- **定义 276（NCQ 总览）**：`NCQ = (NPE, CB, QSim, QAlloc, QRAS, QCert, CG, RC)`。定位：SimRAS 的「模型中心」升级为「需求中心」。不变式：需求抽取、契约求解、重签契约只在语义流；实时流只做量化推理、契约守护的轻量判定、漂移统计，零在线训练写操作。
- **定义 277（需求契约）**：`C_user = (R_max, L_max, E_min, P_min, h_max) ∈ ℝ^5_+`。语义分别为：允许违规概率上界、单步延迟上界（ms）、最低解释深度 `E_min ∈ {0,1,2,3}`、隐私级别 `P_min ∈ {local, edge, cloud}`、最小人类监督间隔 `h_max`（秒）。
- **定义 278（需求偏好后验）**：设用户真实效用由 `θ` 参数化。通过成对偏好查询 `D_pref = {(a_i ≻ b_i)}` 维护后验 `P(θ | D_pref)`，用贝叶斯偏好优化更新；查询选择用 Thompson sampling 最大化期望信息增益 `I(θ; a_i ≻ b_i | D_pref)`。
- **定义 279（需求效用）**：`U_θ(τ) = w_s(θ)·S(τ) - w_l(θ)·L(τ) - w_e(θ)·(E_req - E(τ))_+ - w_p(θ)·privacy_penalty(τ)`。契约 `C_user` 是 `U_θ` 可行域的 lexicographic 近似：安全 ≻ 延迟 ≻ 解释 ≻ 隐私（顺序可由 `θ` 调整）。
- **定义 280（量化配置）**：`b = (b_ERG, b_WM, b_VQA, b_C) ∈ B = {4,8,16}^4`（权重位宽，激活位宽另设）。量化算子 `Q_b(θ_m) = θ_m + e_m(b)`。
- **定义 281（量化误差界）**：对模块 `m`，`E[||e_m(b)||_2] ≤ ε_m(b)`，且 `ε_m` 对 `b` 单调不增。置信上界由 QSim 在 `D_sim` 上统计得到。
- **定义 282（误差-风险传播）**：若 `R_emotion` 关于情绪概率是 `κ_emo`-Lipschitz，则 `|R_emotion^q - R_emotion| ≤ κ_emo·ε_ERG(b)`；同理 `|λ^q - λ| ≤ κ_λ·(ε_ERG(b) + ε_WM(b))`。
- **定义 283（量化感知安全裕度）**：`ρ_safe^q(s) = ρ_safe(s) - κ_λ·ε_q(b) - δ_cal`，其中 `δ_cal` 为 Sim2Real 校准残差。认证前缀一律改用 `ρ_safe^q`。
- **定义 284（契约满足）**：`sat(b, C) ⇔ P(risk(τ) > R_max) ≤ α_R ∧ E[L(b)] ≤ L_max ∧ E_explain(b) ≥ E_min ∧ privacy(b) ≥ P_min`。概率由 QSim 在 `D_sim` 上估计并叠加量化误差上界。
- **定义 285（比特分配优化）**：`b* = argmin_{b∈B, sat(b,C)} [ E[L(b)] + μ·E[Energy(b)] + ν·ε_q(b) ]`。`|B| = 4^4 = 256` 时可穷举；更大时用拉格朗日松弛 + 贪心背包，得 `(1-1/e)` 近似。
- **定义 286（QCert 证书）**：`J_NCQ = (J_SimRAS, b, ε_q, margin_comp, contract_id, drift_flag)`。Valid ⇔ `Valid(J_SimRAS) ∧ margin_comp = κ_λ·ε_q(b) + δ_cal ∧ sat(b,C) ∧ drift_flag = False`。
- **定义 287（契约守护 CG）**：运行时监控 realized risk 与延迟。若滑动窗口违规率 `> R_max` 或 P99 延迟 `> L_max`，则升级比特 `b → b + Δ`（`Δ` 为最小升位向量），或回退全精度 SimRAS；升级/回退带迟滞带 `h_guard`。
- **定义 288（需求漂移）**：`d_req(t) = KL(P_obs(τ) || P_contract(τ))`。若 `d_req > τ_drift` 持续 `T_drift` 窗口，标记 `need_drift = True`。
- **定义 289（重签契约 RC）**：漂移触发后，用最少偏好查询重估 `θ` 与 `C_user`；采用迟滞：新契约须在 `U_θ` 上改进 `ΔU_min` 才接受，否则维持旧契约并记录「隐性不满」计数。
- **定义 290（解释深度-量化耦合）**：解释深度 `E` 对应 VQA 的 token 预算与渲染分辨率。`E_min` 越高，`b_VQA` 下界越高或必须卸载到 edge；定义 `E(b, offload)` 与延迟的 Pareto 前沿。
- **定义 291（隐私-量化）**：`P_min` 决定面部 embedding 是否可离设备。若 `P_min = local`，ERG 必须本地量化运行，`b_ERG` 下界由本地误判约束给出，且禁止上传原始 face。
- **定义 292（需求冲突消解）**：当 `{b : sat(b,C)} = ∅` 时，按优先级放松：先放松 `E_min`，再放松 `L_max`，最后才放松 `R_max`；每次放松写入审计日志。`R_max` 为硬约束，不可放松。
- **定义 293（AIC-NCQ 干扰扩充）**：`ℰ_NCQ = ℰ_SimRAS × ℰ_quant`，其中 `ℰ_quant = {量化误差共因, 跨头误差相关, 校准集偏移}`。
- **定义 294（NCQ 在线不变式）**：实时流只含 QRAS（量化 ERG/EFS/C-RAS/ERS + WM 推理）与 CG 轻量监控；QAlloc 与 RC 在语义流异步运行，周期 `≥ 1s`；VQA 依 `E_min` 端上或卸载。
- **定义 295（QSim 量化感知标定）**：用 SimEngine 在 `D_sim` 上对每个候选 `b` 统计 `ε_m(b)`、风险 CDF、延迟；建立查找表 `(b, scene) → (ε_q, risk_CDF, latency)`，供 QAlloc 与 QCert 使用。

## 2. 关键算法骨架

```python
# NPE：需求偏好抽取（语义流）
class NeedsPreferenceElicitor:
    def __init__(self, theta_prior):
        self.post = theta_prior          # P(θ)
    def query(self):
        # Thompson sampling：采一个 θ，选信息增益最大的成对场景
        theta = sample(self.post)
        return argmax_pairs(lambda q: mutual_info(theta, q))
    def update(self, a, b, prefers_a):
        self.post = bayes_preference_update(self.post, a, b, prefers_a)

# CB：把偏好后验压成可验证契约
def build_contract(theta_post):
    theta = posterior_mean(theta_post)
    return Contract(R_max=theta.R_max, L_max=theta.L_max,
                    E_min=theta.E_min, P_min=theta.P_min, h_max=theta.h_max)

# QAlloc：契约约束下的最小成本比特分配
class QuantizationAllocator:
    def __init__(self, qsim, mu=0.1, nu=0.2):
        self.qsim, self.mu, self.nu = qsim, mu, nu
    def allocate(self, C):
        best, best_cost = None, float('inf')
        for b in product([4, 8, 16], repeat=4):
            eps = self.qsim.quant_error(b)
            if not self.qsim.satisfies(b, C, eps):   # sat(b,C)
                continue
            cost = (self.qsim.latency(b) + self.mu*self.qsim.energy(b)
                    + self.nu*eps)
            if cost < best_cost:
                best, best_cost = b, cost
        if best is None:                              # 不可行 → 放松
            return resolve_conflict(C)
        return best

# CG：契约守护（实时流）
class ContractGuardian:
    def __init__(self, C, h_guard=0.2):
        self.C, self.h, self.win = C, h_guard, deque(maxlen=100)
    def observe(self, risk, latency):
        self.win.append((risk, latency))
        viol = sum(r > self.C.R_max for r, _ in self.win) / len(self.win)
        p99 = quantile([l for _, l in self.win], 0.99)
        if viol > self.C.R_max + self.h or p99 > self.C.L_max * (1 + self.h):
            return 'ESCALATE_BITS'
        if viol < self.C.R_max - self.h and p99 < self.C.L_max * (1 - self.h):
            return 'TRY_LOWER_BITS'
        return 'HOLD'

# QCert：量化感知证书
def make_qcert(J_simras, b, eps_q, delta_cal, contract):
    margin = kappa_lambda*eps_q + delta_cal
    valid = (valid_simras(J_simras)
             and contract_satisfied(b, contract, eps_q)
             and not need_drift)
    return J_NCQ(J_simras, b=b, eps_q=eps_q, margin_comp=margin,
                 contract_id=contract.id, drift_flag=need_drift,
                 valid=valid)

# NCQ：在线实时环路
def NCQ_round(M, obs, C):
    V, T, P, L, P_cloud, W_meas, tactile, img, depth, flow = obs
    # 1) 量化 ERG（隐私级别决定是否本地）
    face_gate = M.qerg.recognize(img)          # b = C.b_ERG
    # 2) 量化 WM 滚动
    act_seq = M.vista.ach.propose_actions(M.x_prime(obs), H=M.vista.H, steps=5)
    wm_preds = M.qwm.rollout(M.x_prime(obs), act_seq, k=5)
    # 3) 量化 EFS / C-RAS（裕度用 ρ_safe^q）
    rho = M.vista.fir.signature(M.vista.stage.split(M.vista.residual_log))
    joint_post, _ = M.qefs.synthesize(rho, face_gate, wm_preds)
    k_ras = M.qcsc.certified_prefix(A=M.vista.ach.propose(...),
                                    joint_post=joint_post,
                                    margin=kappa_lambda*C.eps_q + delta_cal)
    # 4) 控制 + 契约守护
    tau_cmd = M.qers.shaping(M.vista.pi_sigma.prefix_dispatch(A[:k_ras]),
                             joint_post, wm_preds)
    action = M.cg.observe(risk_est(joint_post), latency_est(M))
    if action == 'ESCALATE_BITS':
        M.qalloc.escalate(Δ=(0,1,0,0))
    elif action == 'TRY_LOWER_BITS':
        M.qalloc.probe_lower()
    # 5) 异步：漂移检测 + 重签契约
    if M.rc.should_recontract(obs):
        M.rc.recontract()
    return k_ras, tau_cmd, M.cg.status(), C
```

## 3. 推导

**引理 13（量化误差的风险界）** 设 `R_emotion` 关于 `π` 是 `κ_emo`-Lipschitz、`λ` 关于 `(R_emotion, H_fault)` 是 `κ_λ`-Lipschitz，则 `|λ^q - λ| ≤ κ_λ(κ_emo·ε_ERG + ε_WM) =: κ_λ·ε_q(b)`。因此只要证书使用 `ρ_safe^q = ρ_safe - κ_λ·ε_q - δ_cal`，量化就不会「偷走」安全裕度。

**引理 14（契约可行性蕴含实际满足）** 若 `sat(b,C)` 在 QSim 的置信上界下成立，且 `δ_cal` 覆盖 Sim2Real 残差，则真实部署的违规概率 `≤ R_max + α_q`，其中 `α_q` 由量化误差上界的置信度决定。即：**用保守的 ε 上界换真实的契约满足**。

**定理 14（NCQ 端到端契约一致性）** 在 A87–A91、引理 13–14 及 SimRAS 的定理 11–13 下，NCQ 输出的控制指令满足：
1. `P(|τ_cmd - τ*| > ε) ≤ α_chunk + δ_fi + α_emotion + α_wm + α_vqa + α_q`；
2. `sat(b,C) ⇒ P(risk > R_max) ≤ R_max + α_q`；
3. `P_min = local ⇒ face_embedding` 不出设备，且 `b_ERG ≥ b_local(C)`；
4. `need_drift = True ⇒ drift_flag = True`，证书降级并要求重签契约。

**定理 15（比特分配的近似最优性）** 若各模块的误差/延迟近似可加，则背包松弛给出 `(1-1/e)` 近似；当 `|B| = 256` 时穷举即最优。若 `sat` 可行域为空，则 `resolve_conflict` 的放松序列（`E_min → L_max → R_max`）保证在 `R_max` 硬约束下返回「最不坏」的可行点。

**定理 16（重签契约的稳定性）** 在迟滞阈值 `ΔU_min > 0` 下，重签过程的期望次数满足 `E[N_recontract] ≤ 1 + (d_req/τ_drift)·(1/ΔU_min)`，且不会在两套契约间无限振荡（Lyapunov 型论证）。

**定理 17（解释深度-延迟 Pareto）** 对任意 `E_min`，存在比特配置 `b(E_min)` 使解释延迟落在 Pareto 前沿；端上运行与卸载的交叉点由通信带宽 `B_net` 与 `b_VQA` 共同决定，存在唯一最优卸载阈值。

## 6. 本轮最大风险

**一句话**：NCQ 把「用户需求」当作可由偏好查询可靠抽取、并由契约 `C_user` 忠实表达的稳定对象，但真实用户的**陈述偏好（stated preference）与揭示偏好（revealed preference）常常背离**——用户可能低估自身风险、为性能谎报低 `R_max`、或在疲劳时给出噪声答案；一旦契约建立在错误的 θ 上，量化分配会**精确地满足一份没人真正想要的契约**，形成「安全剧场」：证书 Valid、指标漂亮，却在真实风险偏好下系统性欠安全——这是本轮所有理论依赖的核心假设：**需求可被抽取且契约可被忠实履约**。

## 2. 形式化定义（完整版）

**定义 276（NCQ 总览）** NCQ 是 SimRAS 的「模型中心」升级为「需求中心」：
```
NCQ = (NPE, CB, QSim, QAlloc, QRAS, QCert, CG, RC)
```
不变式：需求抽取、契约求解、重签契约只在语义流；实时流只做量化推理、契约守护的轻量判定、漂移统计，零在线训练写操作。

**定义 277（需求契约）**
```
C_user = (R_max, L_max, E_min, P_min, h_max) ∈ ℝ^5_+
```
语义：允许违规概率上界、单步延迟上界（ms）、最低解释深度 `E_min∈{0,1,2,3}`、隐私级别 `P_min∈{local,edge,cloud}`、最小人类监督间隔 `h_max`（秒）。

**定义 278（需求偏好后验）** 用户真实效用由 `θ` 参数化。成对偏好查询 `D_pref = {(a_i ≻ b_i)}`，维护后验 `P(θ|D_pref)`；查询选择用 Thompson sampling 最大化期望信息增益 `I(θ; a_i ≻ b_i | D_pref)`。

**定义 279（需求效用）**
```
U_θ(τ) = w_s(θ)·S(τ) - w_l(θ)·L(τ)
         - w_e(θ)·(E_req - E(τ))_+ - w_p(θ)·privacy_penalty(τ)
```
契约 `C_user` 是 `U_θ` 可行域的 lexicographic 近似：安全 ≻ 延迟 ≻ 解释 ≻ 隐私。

**定义 280（量化配置）** `b = (b_ERG, b_WM, b_VQA, b_C) ∈ B = {4,8,16}^4`；量化算子 `Q_b(θ_m) = θ_m + e_m(b)`。

**定义 281（量化误差界）** `E[||e_m(b)||_2] ≤ ε_m(b)`，且 `ε_m` 对 `b` 单调不增；置信上界由 QSim 在 `D_sim` 上统计。

**定义 282（误差-风险传播）** 若 `R_emotion` 关于 `π` 是 `κ_emo`-Lipschitz、`λ` 关于 `(R_emotion,H_fault)` 是 `κ_λ`-Lipschitz，则
```
|R_emotion^q - R_emotion| ≤ κ_emo·ε_ERG(b)
|λ^q - λ| ≤ κ_λ·(ε_ERG(b) + ε_WM(b)) =: κ_λ·ε_q(b)
```

**定义 283（量化感知安全裕度）**
```
ρ_safe^q(s) = ρ_safe(s) - κ_λ·ε_q(b) - δ_cal
```
认证前缀一律改用 `ρ_safe^q`。

**定义 284（契约满足）**
```
sat(b,C) ⇔ P(risk(τ) > R_max) ≤ α_R
          ∧ E[L(b)] ≤ L_max
          ∧ E_explain(b) ≥ E_min
          ∧ privacy(b) ≥ P_min
```

**定义 285（比特分配优化）**
```
b* = argmin_{b∈B, sat(b,C)} [ E[L(b)] + μ·E[Energy(b)] + ν·ε_q(b) ]
```
`|B|=256` 时穷举即最优；更大时拉格朗日松弛 + 贪心背包，得 `(1-1/e)` 近似。

**定义 286（QCert 证书）**
```
J_NCQ = (J_SimRAS, b, ε_q, margin_comp, contract_id, drift_flag)
Valid ⇔ Valid(J_SimRAS) ∧ margin_comp = κ_λ·ε_q(b)+δ_cal
        ∧ sat(b,C) ∧ drift_flag = False
```

**定义 287（契约守护 CG）** 监控滑动窗口违规率与 P99 延迟；若 `viol > R_max + h_guard` 或 `P99 > L_max(1+h_guard)`，升级比特 `b→b+Δ` 或回退全精度；若低于下迟滞带则尝试降比特。

**定义 288（需求漂移）** `d_req(t) = KL(P_obs(τ) || P_contract(τ))`；若 `d_req > τ_drift` 持续 `T_drift` 窗口，标记 `need_drift = True`。

**定义 289（重签契约 RC）** 漂移触发后，用最少偏好查询重估 `θ` 与 `C_user`；新契约须在 `U_θ` 上改进 `ΔU_min` 才接受，否则维持旧契约并累计「隐性不满」。

**定义 290（解释深度-量化耦合）** `E_min` 对应 VQA token 预算与渲染分辨率；`E_min` 越高，`b_VQA` 下界越高或必须卸载到 edge。定义 `E(b, offload)` 与延迟的 Pareto 前沿。

**定义 291（隐私-量化）** `P_min=local` 时，ERG 必须本地量化运行，`b_ERG` 下界由本地误判约束给出，禁止上传原始 face。

**定义 292（需求冲突消解）** 当 `{b: sat(b,C)}=∅`，按序放松 `E_min → L_max → R_max`；每次放松写审计日志；`R_max` 为硬约束。

**定义 293（AIC-NCQ 干扰扩充）**
```
ℰ_NCQ = ℰ_SimRAS × ℰ_quant
ℰ_quant = {量化误差共因, 跨头误差相关, 校准集偏移}
```

**定义 294（NCQ 在线不变式）** 实时流只含 QRAS 与 CG；QAlloc/RC 异步运行周期 `≥1s`；VQA 依 `E_min` 端上或卸载。

**定义 295（QSim 量化感知标定）** 在 `D_sim` 上对每个 `b` 统计 `ε_m(b)`、风险 CDF、延迟，建立 `(b, scene) → (ε_q, risk_CDF, latency)` 查找表。

class QuantizationAwareSim:

    def calibrate(self):

            risks, lats = self._rollout_quantized(b) # 量化后风险/延迟

        return (risk_viol <= C.R_max + alpha_q
                and mean(t['latency']) <= C.L_max
                and self._explain_depth(b) >= C.E_min

class QuantizationAllocator:

        self.qsim, self.mu, self.nu = qsim, mu, nu

        for b in product([4, 8, 16], repeat=4):

            if not self.qsim.satisfies(b, C, eps):

                    + self.mu*self.qsim.table[b]['energy']
                    + self.nu*eps)
            if cost < best_cost:

        return best if best is not None else resolve_conflict(C)

class ContractGuardian:
    def __init__(self, C, h_guard=0.2):
        self.C, self.h, self.win = C, h_guard, deque(maxlen=100)
    def observe(self, risk, latency):

        viol = sum(r > self.C.R_max for r, _ in self.win) / len(self.win)
        p99 = quantile([l for _, l in self.win], 0.99)
        if viol > self.C.R_max + self.h or p99 > self.C.L_max*(1+self.h):

class ReContract:

        if expected_utility(new_C) - expected_utility(self.C) > self.dU:

        else:

## 4. 推导

**引理 13（量化误差的风险界）** 设 `R_emotion` 关于 `π` 是 `κ_emo`-Lipschitz、`λ` 关于 `(R_emotion,H_fault)` 是 `κ_λ`-Lipschitz，则 `|λ^q - λ| ≤ κ_λ(κ_emo·ε_ERG + ε_WM) = κ_λ·ε_q(b)`。故证书使用 `ρ_safe^q = ρ_safe - κ_λ·ε_q - δ_cal` 时，量化不会偷走安全裕度。

**引理 14（契约可行性蕴含实际满足）** 若 `sat(b,C)` 在 QSim 置信上界下成立、`δ_cal` 覆盖 Sim2Real 残差，则真实违规概率 `≤ R_max + α_q`，`α_q` 由量化误差上界的置信度决定。即「用保守 ε 上界换真实契约满足」。

**定理 14（NCQ 端到端契约一致性）** 在 A87–A91、引理 13–14 及定理 11–13 下：
1. `P(|τ_cmd - τ*| > ε) ≤ α_chunk + δ_fi + α_emotion + α_wm + α_vqa + α_q`；
2. `sat(b,C) ⇒ P(risk > R_max) ≤ R_max + α_q`；
3. `P_min = local ⇒ face_embedding` 不出设备，且 `b_ERG ≥ b_local(C)`；
4. `need_drift = True ⇒ drift_flag = True`，证书降级并要求重签契约。

**定理 15（比特分配的近似最优性）** 若各模块误差/延迟近似可加，则背包松弛给出 `(1-1/e)` 近似；`|B|=256` 时穷举即最优。若可行域为空，放松序列 `E_min→L_max→R_max` 在 `R_max` 硬约束下返回「最不坏」可行点。

**定理 16（重签契约的稳定性）** 在迟滞阈值 `ΔU_min > 0` 下，`E[N_recontract] ≤ 1 + (d_req/τ_drift)·(1/ΔU_min)`，且不会在两套契约间无限振荡（Lyapunov 型论证）。

**定理 17（解释深度-延迟 Pareto）** 对任意 `E_min`，存在 `b(E_min)` 使解释延迟落在 Pareto 前沿；端上运行与卸载的交叉点由通信带宽 `B_net` 与 `b_VQA` 共同决定，存在唯一最优卸载阈值。

## 7. 本轮最大风险

**一句话**：NCQ 把「用户需求」当作可由偏好查询可靠抽取、并由契约 `C_user` 忠实表达的稳定对象，但真实用户的**陈述偏好与揭示偏好常常背离**——用户可能低估自身风险、为性能谎报低 `R_max`、或在疲劳时给出噪声答案；一旦契约建立在错误的 θ 上，量化分配会**精确地满足一份没人真正想要的契约**，形成「安全剧场」：证书 Valid、指标漂亮，却在真实风险偏好下系统性欠安全——这是本轮所有理论依赖的核心假设：**需求可被抽取且契约可被忠实履约**。
