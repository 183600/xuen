# 第 3 轮迭代（灵感循环 v3：「指标体系」×「用户共创」）—— 评分表不是尺子，而是一份缺页的台账

> **本轮换问题，不是再加一个模块。** 前两轮问的是"策略怎么在接口内变强"；本轮问的是"我们到底在被什么尺子量、这把尺子漏掉了什么"。一句话结论：**官方 `generalization` 字段不是按"轴"编号的，而是按"扰动实例"编号的；`human_1` / `human_4` 里同时混着"赛前挪物"和"中途撤回"。** 因此，任何按 key 名做的覆盖率统计都会高估"撤回型"、低估"位移型"；而真正的空白——撤回、遮挡、背景——只能靠**人**来补。这正好把「指标体系」与「用户共创」接成同一件事。

### 0.1 最关键的一条：key 后缀不是轴

把 60 条 `human_1` / `human_4` 逐条读完后，会发现两类语义在**两个 key 里都出现**：

- `human_1` 里既有"杯子向后""水果向前"（位移），也有"拧开盖子之后拧动回来"（撤回）、"抓到书后挪动架子"（中途干扰）、"可乐快到了然后放回传送带起点"（撤回）。
- `human_4` 里既有"把瓶子向左移动""书向右"（位移），也有"中途把锁拿走""叠完的毛巾翻开""拉上拉链之后拉开"（撤回）。

所以：

1. **不能把 `human_1` / `human_4` 当成两条语义轴**；它们更像"第 1 个/第 4 个扰动实例"。
2. **更不能把 `human_*` 统一当成"撤回"**。按作者语义标注（非官方），60 条里约 **44 条位移型**、约 **15 条撤回/移除型**、1 条环境改变型；若把 T26 的两处"移开"也算移除型，则撤回型约 17 条。撤回型集中在 **13 个任务**（T05、T08、T10、T11、T12、T14、T16、T17、T19、T24、T25、T27、T29）。
3. 这直接改写数据策略：**位移型是"量大、便宜、可增广"的多数派；撤回型是"量小、昂贵、最伤步骤分"的少数派。** v2 把注意力几乎全押在撤回型上，方向对，但**规模估计错了**。

### 0.2 第二关键的一条：step score 可能不是独立维度

榜单"综合成功率与步骤分"的排序口径，并不等于两个独立轴。若失败 episode 的平均得分率为

```text
ρ = E[(step - success) / (1 - success)]        # 失败时仍拿到的步骤分比例
```

则有近似 `step ≈ success + (1 - success) · ρ`。只要 ρ 不大，step 就几乎是 success 的单调变换，**排名信息主要来自 success**。工作区里的占位 fixture 恰好呈现这种关系（pooled R²≈0.995），但 fixture 是合成的，不能据此下结论。因此本轮把它降级为**待检验假设**：设计 E307，等真实榜单/真实 step 口径公开后再判定。若 R² 确实很高，就应把"刷步骤分"的预算转去"补类型覆盖 + 守底线"；若不高，step 才是真正的第二轴，再回到 v2 的安全网。

### 0.3 第三关键的一条：平均分不是中性的

官方平均分 `A_task = (1/N) Σ_t s_t` 等价于按扰动类型加权：

```text
A_task = Σ_y w_y · A_y ,   w_y = |T_y| / N
```

`w_y` 由**测试集里该类型出现多少任务**决定，而不是由**该类型对泛化有多重要**决定。于是：

- 位移型任务多（约 30 个任务含位移 note），它的权重天然大；
- 撤回型只有约 13 个任务，权重小，却最能让"已完成进度"归零；
- 遮挡型（X）与背景型（G）在字段里 **0/32**，权重为 0——**根本没被测**。

这不是"数据不够"，而是**指标体系的结构性盲区**。一个模型可以在平均分上很好看，却从未在 X/G 上被考过。谁先把这份缺页台账补出来，谁就能在下一版评测里占先手。

## 1. 上轮清单诊断：哪些升级、哪些修剪

- **升级**：**UIP-09′（扰动撤回检测-重做）** 与 **UIP-12（DRF）** 必须按类型拆开：位移型用便宜增广，撤回型用人类共创。**UIP-14（MSGR）** 从"任务路由"升级为"扰动类型 + 材料类别"双路由。**UIP-15（CSG）** 加"指标感知"：重做只在预期 GAM 收益 > 延迟/可信度代价时触发。

## 2. 两个灵感词的解读（先直觉，再严谨）

### 2.1 指标体系：一把缺刻度的尺子

**直觉**：如果尺子上"位移"刻了 44 格、"撤回"只刻了 15 格、"遮挡/背景"一格没刻，你会不自觉地优化那 44 格。不是因为你认为它最重要，而是因为**它最容易在表上留下痕迹**。平均分也是这样：它按测试集的构成投票，而不是按泛化的重要性投票。

**严谨定义**：

- 设任务 `t` 的语义类型集合为 `Y(t) ⊆ {D, R, B, E, U, X, G}`（位移 / 撤回 / 底座移动 / 环境改变 / 未见物品 / 遮挡干扰 / 背景场景）。
- 类型均值 `A_y(m) = mean_{t: y∈Y(t)} s_{m,t}`。
- 类型平衡分 `B(m) = mean_{y∈Y_obs} A_y(m)`，`Y_obs` 为至少有一个任务观测到的类型。
- 底线分 `C_β(m) = mean of worst ⌈βN⌉ tasks`（取 β=0.25，即最差 8 个任务）。
- 泛化指标 `GAM(m) = λ·B(m) + (1-λ)·C_β(m)`（默认 λ=0.5）。
- **覆盖债务** `D(m) = {(y,t): y∈Y(t) 但该格无可靠评测}` 必须**显式列出**，不能用 0 或 100 插补。

这样，指标从"平均分"变成"类型平衡 + 底线 + 债务清单"三件事。它不追求一个更漂亮的单数，而是逼你把"没测到的"写出来。

### 2.2 用户共创：让人来画缺失的刻度

**直觉**：缺的刻度不是模型能画出来的。什么叫"自然地把锁拿走"、什么叫"叠完再翻开"，只有做过这件事的人知道；60 条 note 里"移开"到底是赛前还是中途，也只有人能判。于是"用户共创"不是产品口号，而是**指标构建与数据生成的方法论**：人既是**标注者**，也是**扰动发生器**，还是**评分卡的共同作者**。

**严谨定义**：

- **角色**：`actor`（执行扰动的人）、`demonstrator`（演示恢复的人）、`annotator`（标注子目标与类型的人）、`referee`（裁决分歧的人）。
- **扰动语法** `G = {D, R, B, E, U, X, G}`，每条规则带参数（对象、方向、距离、时机、持续时长）。
- **共创循环**：`标注 60+23 条 note → 冻结台账 v1 → 用台账选高价值缺口 → 人生成 R/X/G 演示 → 双盲标注 → 更新台账 v2`。
- **一致性**：用 Fleiss κ / Krippendorff α 监控标注一致性；低于阈值就改 codebook，而不是硬训。
- **合规边界**：共创只发生在**离线数据/标注/评分卡**层；推理期仍然只有一个模型，不引入外部大模型裁判。

## 3. 瓶颈假设（更新）

- **H1（最高杠杆）**：真正的盲区是**类型不平衡 + 类型缺失**，不是平均分不够高。平均分把权重给了容易的类型，把 X/G 的权重设成 0。
- **H2**：`step` 很可能是 `success` 的近似单调变换；在真实口径公开前，不应把"刷步骤分"当第一目标。需要 E307 直接检验。
- **H3**：撤回型（R）只占 human note 的约 25%，但它能**反向消耗**已完成进度，是"少数派高杠杆"；位移型（D）是多数派，适合便宜增广。
- **H4**：X（遮挡/干扰物）与 G（背景/场景）在公开字段里 0/32，靠现有数据永远测不到；只能靠用户共创的变体集补。
- **H5**：语义标注本身会引入新的主观性；没有 κ/α、双盲与版本化，"补轴"会变成"按好补的方式补"，制造新的 Goodhart。

## 2. UIP-16 · GAM（Generalization-Aware Metric）

### 2.1 定义

给定模型 `m`、任务 `t`、类型 `y`：

```text
s_{m,t} ∈ [0,1]        # 成功率
p_{m,t} ∈ [0,1]        # 步骤分（满分归一）
Y(t) ⊆ {D,R,B,E,U,X,G} # 语义类型集合（可多标签）

A_y(m) = mean_{t: y∈Y(t)} s_{m,t}                  # 类型均值
B(m)   = mean_{y∈Y_obs} A_y(m)                     # 类型平衡分
C_β(m) = mean of worst ⌈βN⌉ tasks (β=0.25)         # 底线/CVaR
GAM(m) = λ·B(m) + (1-λ)·C_β(m)      (λ=0.5 默认)   # 泛化指标
```

**覆盖债务**（不参与打分，但必须随分数一起公布）：

```text
Debt = { (y,t) : y∈Y(t) 且该格没有可靠评测 }
Missing = { y : 没有任何任务能可靠测 y }            # 本轮：X、G
```

### 2.2 为什么不是"又一个加权平均"

- 裸平均 `A_task` 的隐含权重是 `w_y=|T_y|/N`；GAM 的 `B` 让每个已观测类型**等权**，避免"位移任务多 → 位移权重天然大"。
- `C_β` 直接惩罚"平均好看、底线很差"的模型。真实榜单若只排平均，会奖励"放弃最难几个任务"的策略；GAM 把最差 25% 显式计入。
- `Debt/Missing` 把"没测到"变成一等公民，防止用 0 或 100 插补制造虚假覆盖。

### 2.3 Goodhart 护栏

- **并列展示**：`success` 与 `step` 分开报；step 只在 success 差 ≤ ε（默认 0.5pp）时作平局裁决。
- **步骤膨胀** `SI = (p - s) - (1-s)·ρ_field`：若某模型的 step 明显高于"由 success 预期的部分"，检查是否在刷早期易得分步骤。
- **类型回归** `TRR = max_y (A_y^field - A_y(m))`：单看"最弱类型"落后多少，防止平均分掩盖类型短板。
- **排名漂移** `Δrank = rank(A_task) - rank(GAM)`：漂移大说明裸平均确实在隐藏东西；漂移小则说明当前类型分层还不够细，需要回到 SPL 改 codebook。

### 2.4 伪代码

```python
OBS = ["D", "R", "B", "E", "U"]          # 本轮可观测；X/G 记入 Missing

def gam(model, tasks, labels, beta=0.25, lam=0.5, eps=0.005):
    s = {t: model.success[t] for t in tasks}
    p = {t: model.step[t]    for t in tasks}

    A = {}
    for y in OBS:
        ts = [t for t in tasks if y in labels[t]]
        if ts:
            A[y] = mean(s[t] for t in ts)          # 类型均值
    B = mean(A.values())                            # 类型平衡
    k = max(1, ceil(beta * len(tasks)))
    C = mean(sorted(s.values())[:k])                # 底线

    score = lam * B + (1 - lam) * C
    debt  = {(y, t) for t in tasks for y in labels[t] if t not in reliable[t]}
    missing = {y for y in "DRBEUXG" if y not in A}
    return {
        "gam": score, "type_macro": A, "balanced": B, "floor": C,
        "debt": sorted(debt), "missing": sorted(missing),
        "rank_gap": rank_taskavg(model) - rank_gam(model),
    }
```

## 3. UIP-17 · SPL（Semantic Perturbation Ledger）与共创标注协议

### 3.1 构建流程

1. **抽 note**：从 32 个 `info.json` 抽 60 条 `human_*` + 23 条 `unseen_object_3`（T31/T32 为空，标 `NO_NOTE`）。
2. **三盲标注**：3 名标注者独立按 codebook 标 `{D,R,B,E,U,X,G,?}`；允许多标签。
3. **一致性检查**：算 Fleiss κ / Krippendorff α；`α<0.7` 的条目进入仲裁，修订 codebook 后重标。
4. **冻结 v1**：把台账写进仓库，带版本号与 codebook 快照；后续只能通过 PR 式补丁修改。
5. **驱动采集**：按 §1.3 的债务清单排优先级（见 3.2），交给 HDR/CSC 去补。

### 3.2 采集优先级（无真实榜单时的先验）

```text
priority(t, y) = w_task(t) × rarity(y) × reversibility(y) × ambiguity(t,y)
```

- `w_task(t)`：该任务计分点里最大单步分值（末步通常 ≥ 前序步）。
- `rarity(y)`：R/X/G 高，D/U 低。
- `reversibility(y)`：R=1、B=0.8、X/G=0.7、U=0.5、D=0.3（能否把已完成进度归零）。
- `ambiguity(t,y)`：标注分歧/文本模糊程度（来自 3.1 的 α）。

**首批优先任务**：T12（开锁/中途拿走）、T14（拧回）、T16（叠完翻开）、T19（拉上拉开）、T26（插口移开）、T27（叠第二后拿下）。它们同时具备高末步权重与明确 R 语义。

### 3.3 台账的副作用

台账一旦公开，就会成为新的优化目标。必须同时公布 **codebook、κ/α、版本号、未决条目**；否则"补轴"会变成"按标注者偏好补"。这是 UIP-19 的职责。

## 4. UIP-18 · HDR（Human Disturbance Repertoire / 用户共创扰动库）

### 4.1 机制

UIP-12 的脚本化 DRF 负责**规模**（D/U 的几何增广、批量生成）；HDR 负责**真实性与缺失类型**（R/X/G），因为这三类很难脚本化，且公开数据为零。

**角色与流程**：

```text
actor：看策略 rollout，选择时机 t* 与扰动 g∈G，执行之
demonstrator：在扰动后演示恢复（同一人或另一人）
annotator：盲标 pre/post 的子目标状态与类型
referee：裁决分歧，维护 codebook
```

**主动对手目标**：

```text
t* = argmax_t  P(g_t done) · w_{g_t}
Δ  = Σ_g w_g · 1[g 被撤回]
选使 E[Δ] 最大的扰动；优先撤回"已完成、且分值最高"的子目标
```

### 4.2 数据 schema

```json
{
  "task": "T12",
  "phase": "before|during",
  "g_before": ["grasp_lock", "insert_key"],
  "intervention": {"type": "R", "primitive": "remove", "object": "lock",
                   "t": 4.2, "params": {"dist": 0.10, "dir": "left"}},
  "g_after": ["grasp_lock"],
  "recovery": {"trajectory": "…", "success": true, "frames": 87},
  "labels": {"D": 0, "R": 1, "B": 0, "E": 0, "U": 0, "X": 0, "G": 0},
  "actor_id": "A03", "naturalness": 4.5, "notes": "…"
}
```

### 4.3 与 UIP-12 的分工

| 类型 | 生成方式 | 目的 |
|---|---|---|
| D、U | 脚本/几何增广（DRF） | 走量、覆盖多数派 |
| R、B、E | 脚本 + 人演（HDR） | 真实撤回/移动 |
| X、G | 人制变体（HDR + CSC） | 补 0/32 的字段空白 |

### 4.4 评价指标

- **恢复成功率 RS**：受扰 episode 最终完成的比例。
- **恢复保留率 RR**：`扰动后步骤分 / 扰动前步骤分`。
- **恢复时延 TTR**：从扰动到重新完成该子目标的步数/秒数。
- **步骤损失 SL**：`扰动前已完成分值 - 扰动后最终得分`。

## 5. UIP-19 · CSC（Co-created Scorecard / 共创式评分卡）

### 5.1 三件事

1. **共创 rubric**：用户/标注者提出子目标定义与边界案例（例如"盖子拧回多少算 regressed"），referee 合并成 codebook v1；每次修改留痕。
2. **双盲标注**：人类标注与 UIP-11 GSO 的几何谓词**互相独立**地判 `done/ongoing/regressed`；报告 Cohen κ / Krippendorff α。低一致性优先归因于 rubric 模糊，而不是模型失败。
3. **用户自制变体**：用户用自家杯子/文具/包/桌面，拍 5–10 个任务变体，标注 X/G/U 类型；作为**held-out 共创测试集**，专门测公开字段缺失的轴。

### 5.2 Goodhart 审计

每次榜单/内部评测更新后，回答三个问题：

- 步骤分上涨是来自**新成功**，还是来自**部分分农场**？看 `Δp/Δs` 与 `SI`。
- 平均分上涨是否伴随**底线下降**？看 `C_β` 与最差 25% 任务。
- 类型平衡分上涨是否伴随**某类型回归**？看 `TRR` 与 `A_y` 分解。

### 5.3 评分卡版本化

```text
scorecard/
  codebook_v1.md
  ledger_v1.json
  variants/          # 用户自制变体（图片/状态/标签）
  annotations/       # 双盲标注与 κ/α
  reports/           # 每次评测的 metric card
```

## 6. 旧条目升级细则

### 6.1 UIP-02″（原 SSG，降级）

- **保留**：按真实计分点有序推进，别把已完成的前置步骤弄丢。
- **降级**：不再把 step 当独立第二轴；step 只作并列展示与平局裁决。
- **触发条件**：只有当 E307 证明 `step` 与 `success` 的 R² 明显低于 ~0.98 时，才恢复到 v2 的"步骤分安全网"权重。

### 6.2 UIP-14′（MSGR-T，类型-材料双路由）

- 第一层路由：**扰动类型**（D/R/B/E/U/X/G）→ 选恢复/增广策略；
- 第二层路由：**材料/机构类别**（刚性/可变形/插入/铰链/流体/细软/堆叠）→ 选技能头；
- 共享骨干 + 参数高效适配器，仍满足"单模型多任务"；不做 32 个独立模型。
- 依据：任务级差异远大于材料级差异，材料类只能解释一部分路由收益；因此**材料类做粗路由，任务级用轻量适配器**，不要指望一个材料专家吃下所有任务。

### 6.3 UIP-15′（CSG-M，指标感知安全阀）

```text
redo_allowed  ⇔  E[GAM_gain] > α·latency_cost + β·credibility_risk
```

- 重做/重试仍受最大次数、置信度门限、延迟预算约束；
- 但新增"底线保护"：如果当前任务属于最差 25%，允许更高的重做预算；如果属于已稳的头部任务，收紧预算防止拖慢。

### 6.4 UIP-12（DRF，拆分）

- **DRF-S（scripted）**：D/U 的几何增广、批量生成；
- **DRF-H（human）**：R/B/E/X/G，交给 UIP-18 HDR；
- 二者共享同一 schema 与同一套评价指标，便于合并训练。

## 8. 占位 fixture 的方法学压力测试（**合成数据，勿当真**）

数据：`exp/official/leaderboard_data.json`（`generated_from: gen_leaderboard.py`；8 个合成模型 × 32 任务；顶部 avg success=29.7，**不是官方真实排名**）。

| 检查 | 结果 | 说明 |
|---|---|---|
| `step ~ success` 合并回归 | 斜率 1.337，截距 0.093，**R²=0.9955**，Pearson 0.9977 | 合成器让 step 近似 success 的仿射变换；**不能证明真实榜单也如此** |
| 失败 episode 的平均得分率 ρ | 8.91–14.54 / 100，均值 **11.55** | 失败多发生在早期；步骤分溢价主要来自"成功 episode 拿满 + 失败拿少量" |
| 裸平均排序 | Molmo > WALL > DreamZero > Spirit > DM0 > PI > Giga > GR00T | 与 fixture 的 `generalist` 顺序一致 |
| 底线排序（最差 8 任务） | Molmo > WALL > DreamZero > Spirit > Giga > DM0 > PI > GR00T | Giga 从第 7 升到第 5，DM0/PI 后移 |
| 最差单任务排序 | Molmo > WALL > DreamZero > Giga > PI > DM0 > Spirit > GR00T | **Spirit 从第 4 掉到第 7**；说明平均会掩盖底线 |
| 类型平衡排序（D/R/U 等权） | Molmo > WALL > DreamZero > Spirit > DM0 > Giga > PI > GR00T | 变化较小：fixture 的类型分层不够细，需真实数据重做 |

**结论（仅方法学）**：GAM 的**底线项**对排序的影响最大；类型平衡项在合成 fixture 上区分度有限，说明 SPL 的 codebook 还需要更细的类型（或真实榜单）才能发挥作用。这反过来支持 E301/E307 的必要性。

## 9. 合规、伦理与风险

- **单模型合规**：HDR/CSC 都是**离线数据、标注、评分卡**，推理期仍只有一个模型；不引入外部 VLM 裁判。
- **人类受试者**：扰动演员/标注者需知情同意、合理补偿；不采集个人身份信息；变体数据脱敏。
- **标注偏差**：用三盲、κ/α、codebook 版本化、未决条目公开来抑制"按好补的方式补"。
- **仿真过拟合**：HDR 在仿真里生成的 R/X/G 仍需真机锚点；E303/E306 必须留真机时段。
- **占位 fixture 陷阱**：`generated_from: gen_leaderboard.py` 的数据只能做公式压力测试；任何"榜首<30%""step 与 success 独立/不独立"的真实结论都必须等官方数据。
- **Goodhart**：GAM 一旦公开，也会被优化；因此同时公布分项、底线、债务与 codebook，避免单数指标独裁。

## 11. 本轮押注与风险

**→ 押注：UIP-17 SPL × UIP-18 HDR × UIP-19 CSC 的"共创补轴闭环"，由 UIP-16 GAM 统一度量。** 它不追求把平均分再抬几个点，而是先把"尺子缺了哪些刻度"写清楚，再用人类补上 X/G 与 R 型这些公开数据为零、却最能让进度归零的格子。

**本轮最大风险（一句话）**：把"语义标注 + 合成 fixture"当成真实赛制证据，导致补轴补在错误方向上；必须以官方手册/真机为锚，把标注与 fixture 都只当假设生成器，而不是结论本身。
