## 1. 直觉（三个灵感的碰撞）

**灵感 1（研究空白 → 第一件事是证伪自己）**
直觉：上一轮我几乎要把「技能基 LoRA」写成 I10。检索后发现 PRISM（3 周前）已把「per-skill LoRA primitive bank + per-chunk router」做完，并在 RoboCasa365 把 composite 从 17.5% 提到 20.0%；MAST-VLA 做了 skill-conditioned LoRA-MoE；SMoDP、gated experts 把负迁移门控也占了。**研究空白的反直觉点：你看到的空白，通常只是你还没读到的论文。** 所以本轮的方法论产出不是「加模块」，而是把 I10 从「技能基」修剪成「合规且未被占坑的窄缝」——空白不是地图上的白区，而是一个必须同时通过先验覆盖、计分轴、单模型合规、预算四道检验的*可主张差异*。

**灵感 2（参数高效微调 → 不是压缩，是实验仪器）**
直觉：PEFT 的通常叙事是省显存；但在本赛制里它更重要的属性是**单次实验便宜**（官方 frozen-VLM/LoRA 单卡 24GB、现成 yaml，F11/F26）。当「改一个变量」从 8 卡全参降到单卡数小时，瓶颈就从算力转移到*测量*：可以在同一预算内做设计好的序贯实验（rank、target module、merge 方式、数据配方），把 I8 的离线-在线注册表真正喂满。**PEFT 的价值不是让模型更小，而是让「假设→证据」的循环更短。** 这也修正 Round 2 的「数据 > 模型」：数据决定上限，PEFT 决定你多快知道上限在哪。

**灵感 3（碰撞 → 唯一未被占的窄缝：单模型约束下的 maximin 秩预算 + 合并）**
直觉：PRISM/MAST 都依赖**推理期在 adapter 库上路由**——在本赛制里可能被裁定为「多模型/集成」，触碰 PR2 单模型边界；且它们假设预定义技能分类与可观测 phase，而本赛题只有每 episode 一条 language，无 phase 标签、无 phase 边界。两个约束叠加，真正未被占的格子是：**固定总秩 R、训练期可分解、推理期合并成单一权重、目标为最大化最差任务（maximin）的 LoRA 预算分配**。它不是 PRISM 的复刻，而是 PRISM 的「合规对偶」。

**三者统一**：研究空白负责「删」（砍掉已被占坑的技能基），PEFT 负责「测」（廉价探针喂注册表），maximin 合并负责「补」（单模型约束内唯一的参数级增量）。本轮结论：**模型侧只剩一条窄缝，且期望增益小于数据引擎；把 PEFT 当仪器用，比当创新点用更值。**

## 2. 严谨定义

**定义 1（可主张的研究空白）**：设方法空间 M、先验证据集 E。候选创新点 x∈M 是可主张空白，当且仅当：
1. **覆盖性**：不存在 e∈E 在「可比 regime」（同任务族、同约束、同目标函数至少两项相同）实现 x 的核心机制；
2. **计分性**：x 的差异维度落在官方计分轴（成功率 / 步骤分 / 5 类泛化轴）；
3. **合规性**：x 不违反单模型、无在线学习、接口约束；
4. **杠杆性**：E[Δscore]/E[cost] 不低于当前主押注的边际。
只满足「无人做」而不满足 2–4 的，是**注意力空白**（attention gap），不是**能力空白**（capability gap）。本轮判定：「技能基 LoRA」= 注意力空白（F20/F21 已占）；「单模型 maximin 合并」= 能力空白候选（待 L0）。

**定义 2（PEFT 合并 vs 路由）**：冻结基座 W0，LoRA 适配 ΔW=BA，A∈R^{r×d_in}、B∈R^{d_out×r}。多家族 {ΔW_t} 的**合并**为 ΔW*=Merge({ΔW_t})，推理 W=W0+ΔW*；**路由**为 W=W0+ΔW_{π(chunk)}。PRISM/MAST 是路由；本点只允许合并（单模型）。maximin 目标：
  max_{r_t} min_t S_t(W0+Merge({ΔW_t(r_t)}))  s.t.  Σ_t r_t ≤ R。
**子空间重叠** ρ_ij=||U_i^T U_j||_F^2 / min(r_i,r_j)（U 为 ΔW 主奇异子空间）；合并对任务 j 的一阶干扰代理 ∝ ||J_j||·||ΔW_i||·√ρ_ij。ρ 是可测的合并风险指标（非严格定理）。

**定义 3（PEFT 作为仪器）**：一次探针 = (r, target_module, data_mix) → 单卡 ≤1 GPU-day 的 LoRA run。仪器有效性 = 探针排序与真机增益的 Spearman 相关；目标是让该相关 >0.6 所需真机样本数最小。

## 1. 创新点清单

### I10 单模型 maximin 秩预算 + 正交合并（新，★★★）
- **动机**：P1 弱任务支配；模型侧唯一未被占且合规的窄缝（§0）；F20–F24 的占坑审计把原「技能基」方案修剪至此。
- **与现有方案差异**：① PRISM/MAST 推理期路由多个 adapter → 可能违反单模型；本点训练期分家族、推理期合并为单一 ΔW*。② 目标从「平均成功率」改为「maximin 最差任务步骤分」。③ 数据来自 I2 孪生语料，负迁移以家族为隔离粒度。
- **技术可行性**：中。官方 LoRA 配置现成（F26），单卡探针 ≤1 GPU-day；合并用 TIES/正交化 + 短 healing；maximin 用二分水位法。
- **所需资源**：6–10 个探针（1×24GB，2 GPU-days）+ 1 次合并/家族 L0；无新增数据。
- **落地步骤**：①r∈{8,16,32} × 2 弱任务探针；②拟合 g_t(r)（家族级边际增益曲线）；③水位法分配 Σr_t≤R；④分家族训练 → 正交/TIES 合并 → healing（低 LR、32 任务、≤500 step）；⑤L0：合并 vs 朴素相加 vs 均匀 rank；⑥L2：top-1 真机 2 任务 × 2 次。
- **风险**：合并干扰 > 分配增益（缓解：ρ 重叠诊断 + healing + 退化为单 LoRA）；rank 收益不可加（缓解：只信实测 g_t(r)，不做外推）；单模型裁定（缓解：默认合并，路由方案仅在书面许可后启用）；挤占 I8 预算（缓解：探针同时作为 I8 数据点，双重用途）。
- **降级/裁撤判据**：若 L0 的 maximin 增益 <1 个步骤分，砍掉 I10 创新点，仅保留「PEFT 探针」作为 I8 仪器。

### I1 v2 考纲校准五轴增广引擎 ★★★★★（维持）
- **动机**：320 次真机评测每次都在 5 轴偏离训练分布（P2/F2）；泛化缺口是全局乘性损失。
- **做法**：每任务一张「考纲卡」（位置半径、干扰物类型、背景纹理集、未见物品类别/外观范围），增广参数从考纲卡采样；每轴 3 档剂量（考纲内/边缘/外），官方示例截图作锚点。
- **差异**：直接 SFT 用标称数据；盲目增广用无校准随机化；本点把增广对准计分轴（PR1/PR5）。
- **资源/步骤**：分割+inpainting 1×24GB；32 张考纲卡 → 背景/干扰物放量 → 外观/位置 L0 → 剂量定档 → 位置×干扰物析因。
- **风险**：考纲卡偏差（单任务通道抽测 + 示例对齐）；位置重拼接物理不可行（L0「不可行动作占比」>5% 降级为平移不变增广）。

### I2 v2 数据引擎 2.0：110 语料孪生迁移 + 加权共训 ★★★★★（主押注）
- **动机**：单模型平均分被最弱任务支配（P1）；示教语料与质量双重浪费（P8）。
- **做法**：①孪生表选 110 语料入训；②patch 官方 loader 实现族级权重（32 全量 / 孪生半权 / 远任务 ≤5%）；③示教质量加权（进度效率 × 平滑度 × 成功裕度），剪最差 10%。
- **差异**：均匀混训浪费容量；本点诊断先行、孪生定向、权重受控。
- **资源**：孪生子集 ≈1–2TB + 32 任务 ≈2TB；1×24GB 起步、8×A100 上限。

### 2.1 maximin 秩分配（I10）
```python
def maximin_rank_alloc(families, base_score, gain_curve, R):
    # gain_curve[t][r]: family t 在秩 r 的实测边际步骤分增益（来自探针，凹且只信实测点）
    # max min_t (base_score[t] + gain_curve[t][r_t])  s.t. sum r_t <= R
    def need_at(lam):
        alloc, need = {}, 0
        for t in families:
            r = max([0] + [k for k, g in enumerate(gain_curve[t])
                          if base_score[t] + g >= lam])
            alloc[t] = r
            need += r
        return need, alloc
    lo = min(base_score)
    hi = max(base_score[t] + max(gain_curve[t]) for t in families)
    best = {t: 0 for t in families}
    for _ in range(40):                      # 二分最差任务水位
        mid = (lo + hi) / 2
        need, alloc = need_at(mid)
        if need <= R:
            best, lo = alloc, mid            # 可行则抬水位
        else:
            hi = mid
    return best                              # {family: rank}
```
