# 第 2 轮（UniBot 线 · 相对本文件为第 2 轮；本轮灵感：「双臂协作」×「知识图谱」）

> **承接声明**：上一轮已把状态文件重新基线化到 UniBot 世界挑战赛（UniBot-V1 通才赛道，Unitree G1，32 桌面任务），并建立 UniBot-SAGE（接地层 / 技能层 / 适应层 / 工程层）。本轮**不推倒重来**：保留 SAGE 的四层骨架与全部 P0 工程约束，把"双臂"与"关系先验"插入为新的第一性结构。定义 U1–U12、引理 L1–L7、实验 E601–E618 继续有效；本轮新增 U13–U24、L8–L13、E619–E636，新 IP 从 IP-09 起。
> **数据纪律**：榜单数字来自 `unibot.unitree.com/leaderboard_data.json`（teaser/占位表，`generated_from: gen_leaderboard.py`，检索日期 2026-11-22）；只作结构分析，不作真机结论。任务是否"双臂"由语言语义手工弱标注，明确标注为**假设**。

## 0. 这一轮换什么视角（一句话）

上一轮把"通用"拆成技能向量；但技能向量仍默认**每条轨迹是一只手的轨迹**。本轮两个灵感指向同一件事：32 个任务里真正的难点不是"会不会抓"，而是**两只手如何在同一个物体上形成约束**，以及**这些约束能否被一个关系结构复用**。

## 1. 直觉与第一性原理

### 灵感 1 ·「双臂协作」→ 双臂不是两条单臂，而是一个"物体约束系统"

**直觉解释**：单臂操作的自由度是"手怎么动"；双臂操作的自由度是"两只手如何通过物体互相约束"。两只手同时抓住同一个刚性物体时，它们不再是 12 个自由变量，而是被物体"焊"成了一个刚体：一只手的运动必须由另一只手的运动和物体的几何共同决定。真正难的是**角色**（谁稳住、谁操作）、**耦合**（两只手是否真的通过物体连上了）、**时序**（先抓哪只、何时松哪只）和**内力**（两只手会不会互相挤压）。接口恰好把两只手都暴露出来（左右各 7 关节、左右夹爪、左右 EE 位姿、左右腕相机），所以"协作"在原理上可观测；但接口只给 1 维夹爪开合、没有触觉/腕力，所以"耦合的力学质量"不可直接观测。→ 正解不是"训练一个更大的双臂策略"，而是：**(a) 把耦合状态显式化；(b) 用相对位姿约束把 12 维动作降维；(c) 把角色分配做成可验证的离散变量。**

**严谨化（一句话版，完整定义见产物区 U18–U23）**：
- 设左右 EE 位姿为 `T_L, T_R ∈ SE(3)`，相对位姿 `T_rel = T_L^{-1} T_R`。
- 对物体 `o`，定义**耦合流形** `M_o ⊂ SE(3)`：两只手同时抓住 `o` 时，`T_rel` 必须落在的集合。刚性固定抓取时 `M_o` 是一个点（或小邻域）；旋转类物体（瓶盖、钥匙、拉链）时 `M_o` 是一维流形；可变形物体时 `M_o` 是一个分布。
- 定义**耦合残差** `r_c(t) = dist(T_rel(t), M_o)`，**耦合状态** `c_t ∈ {free, one_hand, coupled, slipping, decoupled}`，**角色** `ρ_t ∈ {L_hold/R_operate, L_operate/R_hold, both_hold, independent}`。
- 双臂策略在耦合相位下应满足：`a_R = T_H · π_O(o, a_H)`（操作手在稳定手坐标系里出动作），而不是两只手各自独立回归 6 维 EE 目标。

### 灵感 2 ·「知识图谱」→ 有用的不是"百科图谱"，而是"可供性—角色—约束"图

**直觉解释**：32 个任务不是 32 个孤立标签，它们共享物体属性（刚性/可变形/可旋转/可插入/容器/易碎）、动作原语（抓/捏/推/拉/拧/插/倒/折/拉链/挂/叠）和**双臂角色模板**（谁持、谁操作、谁先松）。一个知识图谱的价值不在于"知道瓶子是什么"，而在于：看到"瓶盖 + 单自由度夹爪 + 旋转目标"时，能检索出"左手持瓶、右手拧盖、约束是一维旋转流形"这个**可执行模板**，并在物体太宽/太滑时沿 `alternative-to` 边退回"推倒/钩/双手捧"等替代方案。更关键的是：图谱是**跨任务复用**的压缩先验——它让"未见物体"通过属性落到已知模板上，而不是要求策略见过每个物体。

**严谨化（一句话版，完整定义见 U13–U17）**：
- 可供性图 `G = (V, E)`，节点类型 = {物体类别, 属性, 动作原语, 任务模式 schema, 相位, 约束, 角色}；边类型 = {requires, enables, precondition, effect, alternative-to, couples-with, role-template}。
- 任务模式 `s = (pattern, preconditions, effects, role_template, phase_order, constraint_manifold)`；`pattern` 是带槽位的子图模板。
- 检索 `s* = argmax_s [Sim(G_scene, pattern_s) + λ log P(s|ℓ)]`；置信度低于 `τ_schema` 时退回通用 schema。
- **合规关键**：图谱节点是"可供性/约束类型"，不是任务 ID；任务身份只从语言指令 `ℓ` 进入；图谱只做 **sound filter**（只删除违反硬几何前条件的方案，不凭空生成方案），不做"读题即硬编码"的分支。

### 合成：SAGE → **BiGraph**（双臂可供性图）

**直觉**：上一轮的 SAGE 是"抓握显式化 + 技能路由 + 推理期适应"；本轮在它上面加两层：
1. **关系层（BAG-KG）**：把"物体属性 → 角色模板 → 约束流形 → 替代方案"编码成图，提供可检索、可验证、可复用的先验；
2. **耦合层（RelFrame + CouplingGuard）**：把两只手的动作写成"稳定手 + 操作手"的相对坐标策略，并把耦合残差作为一等公民监控。

两层与原有 SAGE 的接口是：KG 产出 `z_task` 的语义先验、`z_phase` 的期望顺序、`ρ` 的角色模板、`M_o` 的约束；耦合层产出 `c_t` 与 `r_c`，反馈给 IP-02 的抓握确认与 IP-03 的 chunk 调度。

**一句话**：**SAGE 解决"一只手抓没抓住"，BiGraph 解决"两只手有没有真的通过物体连上、以及这个连接方式能否从别的任务迁移过来"。**

**结论（本轮可执行的四条）**：
- **T1 红利重尾**：路由先攻 top-8 任务（占 54.6% 红利），不要平均用力。
- **T2 双臂是主战场**：高红利任务与双臂弱标注组重叠（Hang the Cup、Disconnect Ethernet、Stack Bowls、Fold Towel、Arrange Test Tubes），且失败集中在"最后耦合/对齐"。
- **T3 图谱只能做粗先验**：家族 oracle 最多吃一半；KG 的价值在"角色/约束模板的可迁移性"和"sound filter"，不是替代 task token。
- **T4 耦合必须先确认再发力**：无触觉/腕力 + 1 维夹爪开合 ⇒ 耦合假阳性的代价不对称，必须保守介入。

## 3. 研究问题（本轮新增 Q6–Q10）

- **Q6（耦合可观测性）**：在只有 1 维夹爪开合、无触觉/腕力的接口下，能否用"相对位姿 + 双腕视觉 + 双夹爪"把 `c_t` 估成带校准置信度的状态，并只在高置信时改变双臂行为？
- **Q7（角色可迁移性）**：角色分配 `ρ_t` 能否从"语言 + 场景图 + 物体属性"检索得到，并在未见物体上保持？错误角色的代价如何被限制？
- **Q8（图谱的 soundness）**：把 KG 限制为"只做硬几何前条件的 sound filter"时，它能删掉多少不可行抓法/角色，又会不会误删可行方案？误删率与覆盖率如何权衡？
- **Q9（相对坐标的降维收益）**：在耦合相位用相对坐标策略（稳定手 + 操作手）相比"两只手各自回归 EE 目标"，样本效率、协调误差、成功率各改善多少？在非耦合相位退回独立策略的切换代价是多少？
- **Q10（两级路由）**：KG 家族先验 + task token 的两级路由，能否在"每任务只有 1–6 个近优模型"的稀疏信号下，比单级 task token 更稳、更省数据？

## 4. 设计原则（在 P1–P6 上追加）

- **P7 耦合显式化**：把 `c_t, r_c, ρ_t` 当作与动作同等重要的输出；任何双臂改动必须能报告"耦合是否建立/保持/丢失"。
- **P8 图谱只做 sound filter**：KG 的硬约束只允许是"必要不充分"的几何/物理条件（如物体宽度 ≤ 夹爪开口、插入轴可见）；禁止用图谱做任务级硬编码；图谱置信度低时一律退回通用 schema。
- **P9 角色可交换、可回退**：`ρ_t` 必须允许"换手/换角色"，且换角色要经过一次耦合残差检查；不允许在耦合未确认时让操作手发力。
- **P10 两级路由**：粗粒度家族（KG）+ 细粒度 task token（语言）+ 角色/相位 token；任何一级置信度低时降级，而不是强行路由。

## 5. 最小可提交闭环（MVP）与退化链

**MVP = BAG-KG（离线建图 + 检索 + sound filter） + CouplingGuard（`c_t/r_c` 估计） + RelFrame（耦合相位的相对坐标策略） + 上一轮的 IP-02/IP-03/IP-06**。

理由：KG 决定"该用哪个角色/约束模板"，CouplingGuard 决定"现在能不能按模板发力"，RelFrame 决定"发力时两只手怎么分工"；三者都不依赖新的真机数据，且直接打在"最后对齐/插入/耦合"这个断点上。

**退化链（新增 Level-5/6/7，原有 Level-0–4 保留）**：
- Level-5 KG 检索置信度低 ⇒ 退回通用 schema（单臂/单阶段先验），不强行套模板；
- Level-6 耦合置信度低或残差超阈 ⇒ 退回独立双臂策略 + 只做单臂任务，禁止"假设已耦合"地发力；
- Level-7 相对坐标策略不可用 ⇒ 退回两只手各自回归 EE 目标的联合策略；
- 任何一级失效都不改变"单 checkpoint、单 API、单模型"的对外形态。

## 6. 预期贡献（可验收）

1. 给出**双臂耦合的可观测化**：`c_t` 的校准曲线、`r_c` 的估计误差、以及"只在高置信时按耦合模板发力"的净收益。
2. 给出**可供性图谱的第一版可执行 schema 库**（至少覆盖旋转/插入/折叠/拉链/挂取/转移六类），并证明它在未见物体上的检索 top-3 命中率与误删率。
3. 量化**相对坐标降维**的收益：耦合相位下动作维度从 12 降到 6+internal，样本效率与协调误差的改善。
4. 给出**两级路由**的可兑现比例：KG 家族先验 + task token 相对单级路由的增益，以及 in-sample 上界（k=5 48%、k=7 57%、k=12 71.5%）的兑现率。
5. 把"图谱只做 sound filter"变成可审计的合规定义：任何被 KG 删掉的方案都有硬几何证据，任何被保留的方案都可追溯到语言/场景，不做任务级硬编码。

## 7. 本轮最大风险

**一句话**：**双臂耦合的力学状态在接口里不可观测（只有 1 维夹爪开合、无腕力/触觉），视觉上"看起来对"的耦合可能在悄悄打滑或互相挤压，而知识图谱又会以高置信度给出错误的角色/约束模板，导致错误被放大且无法在 episode 内被检测到。**

## 8. 下一轮迭代计划（深化与修剪）

- **深化**：把 `c_t` 从离散状态升级为"耦合残差 + 滑移率 + 内力代理"的三维连续量；把 KG 的 `alternative-to` 边与 IP-02 的非抓取原语库合并成一张"失败→替代"图。
- **修剪预案**：若 CouplingGuard 在真机上的 AUROC < 0.8，则**砍掉"按耦合模板发力"**，只保留"耦合残差用于安全回退"；若 KG 检索 top-3 命中率 < 0.6，则把 KG 降级为离线角色标注器，不再在线检索。
- **保留项**：BAG-KG（离线 schema 库）、CouplingGuard（安全回退）、RelFrame（相对坐标）三项在任何情况下不砍；上一轮的 IP-02/IP-03/IP-06 继续保留。

## 0. 本轮结论摘要

**一句话路线**：在 SAGE 的四层骨架上插入**关系层（BAG-KG）**与**耦合层（CouplingGuard + RelFrame）**，把"两只手是否通过物体连上、谁持谁操作、连接约束是什么、失败退到哪"变成可检索、可验证、可回退的显式变量。

**为什么是这两层（teaser 榜 n=256 个 model-task 点的结构证据）**：

## 1. 继承与变更

## 3. 创新点详述

### IP-09 · BAG-KG 双臂可供性图（P0）

- **动机**：32 个任务共享物体属性、动作原语和双臂角色模板；未见物体可以通过属性落到已知模板，而不是要求策略见过每个物体。第 1 轮已证明"通用 = 技能向量"，本轮进一步主张"技能 = 角色 × 相位 × 约束"的组合，图谱是这种组合的压缩表示。
- **与现有方案的差异**：不是百科 KG，也不是把任务说明塞进 prompt。我们建的是**类型化、可执行**的 schema 图：每个 schema 带 `pattern`（带槽位的子图模板）、`preconditions`（硬几何/物理条件）、`effects`、`role_template`（谁持谁操作）、`phase_order`、`constraint_manifold`（`M_s`）和 `alternative-to` 边。图谱同时服务三件事：①在线检索（给策略角色/相位/约束先验）；②sound filter（删掉不可行方案）；③离线伪标（给 IP-01/IP-11 生成角色与耦合标签）。
- **技术可行性**：中–高。本体 v0 可手工建（~30 物体类别 × ~12 可供性 × ~10 动作原语 × ~6 约束类型）；场景图用 VLM + 腕部几何；schema 挖掘用官方数据的"哪只夹爪先闭、哪只臂位移大、`T_rel` 是否稳定"自动生成候选；人工抽检 5%。
- **所需资源**：数据 = 官方 32 数据集；算力 = 小（VLM 打标 + 图嵌入）；接口 = 无新增字段。
- **落地步骤**：①本体 v0（物体/属性/原语/schema/约束/角色）；②场景图抽取器；③schema 挖掘器（从数据自动提角色/相位/约束）；④建图 + 人工抽检；⑤检索器（GNN/嵌入 + 语言先验）；⑥sound filter；⑦离线评测（留出物体属性/任务）；⑧接入策略服务。
- **风险**：①本体覆盖不足 ⇒ 未见属性落不到模板；②VLM 标签噪声 ⇒ 双标注一致性检查；③检索错 schema ⇒ 置信度门控 + 通用 schema 回退；④**合规**：图谱不能有任务 ID 节点，不能按任务名分支 ⇒ 设计上只用属性/原语/角色节点，任务身份只从 `ℓ` 进入，并在提交文档中明示。

### IP-10 · RelFrame 相对坐标双臂策略（P0）

- **动机**：耦合时两只手被物体"焊"住，12 个 EE 自由度实际只对应"物体位姿 + 内部自由度"；让两只手各自回归 6 维目标既浪费样本又容易互相打架。角色通常不对称：一只手稳住（准静态、低频），另一只手操作（动态、高频）。
- **与现有方案的差异**：现有双臂策略多是"两臂联合回归"或"两臂共享一个大模型"；我们把动作分解为**稳定手 `a_H`（低频、准静态）+ 操作手相对动作 `a_O^rel`（高频）**，再用 `a_O = T_H · a_O^rel` 合成。耦合未确认时退回独立双臂策略；角色可交换（`ρ`）。
- **技术可行性**：中–高。`control_space=ee` 时相对变换是精确的；若选 `joint`，用 IP-07 的 IK 代理把相对 EE 动作转成关节目标。稳定手/操作手的划分可用角色标签监督，也可用"哪只臂位移小/夹爪闭合早"自监督。
- **所需资源**：数据 = 官方数据（含双 EE、双夹爪、双腕）；算力 = +20%；接口 = 无（仍是 `action.left_arm/right_arm` 或双 EE）。
- **落地步骤**：①从数据估计每个 schema 的 `M_s`；②在耦合段训练稳定手头与操作手头；③实现相对动作合成与角色交换；④实现非耦合回退；⑤真机 A/B（耦合类任务）。
- **风险**：①相对合成误差在接触后放大 ⇒ 加耦合残差闭环；②稳定手漂移 ⇒ 稳定手也做低频位姿保持；③`joint` 空间的 IK 误差 ⇒ 优先 `ee`，`joint` 仅作备选；④评测端对 `pivot`/双臂跟踪语义未知 ⇒ 先做零成本探测。

### IP-11 · CouplingGuard 耦合确认与安全回退（P0）

- **动机**：接口只有 1 维夹爪开合、无触觉/腕力，耦合的力学质量不可直接观测；而"以为耦合了其实没有"的代价是不对称的——操作手一发力，物体可能被挤飞/滑落，甚至两臂互顶。必须先确认，再发力。
- **与现有方案的差异**：第 1 轮的 GraspVerify 只判"单手抓住没有"；CouplingGuard 判"两只手是否通过物体连上、连得稳不稳"，输出 `c_t`、`r_c`、`p_coupled`，并驱动角色/动作回退。
- **技术可行性**：高。信号全在观测里：`T_rel`、双腕帧、双夹爪、双 EE 速度；标签可从数据自动生成（双夹爪闭合 + `T_rel` 低方差 + 物体随动）；模型用 ResNet/GRU 级即可。
- **所需资源**：数据 = 官方数据；算力 = 小；接口 = 无。
- **落地步骤**：①自动生成耦合/滑移伪标签；②训练 `p_coupled` 与 `r_c` 估计；③校准（可靠性图）；④定义介入准则（高精度、低召回）；⑤与 IP-02/IP-10 联动；⑥真机 A/B。
- **风险**：①内力不可观测 ⇒ 只能保守；②伪标签在未见物体上漂移 ⇒ 置信度门控 + episode 内自校准；③假耦合（以为连上其实没连）代价高 ⇒ `α ≤ 0.01`、最大重试 3 次、失败即回退独立策略；④视觉遮挡 ⇒ 用 EE 运动学补位。

### IP-12 · GraphRouter 两级路由（P1）

- **动机**：路由红利重尾（top-3 占 30.1%，top-8 占 54.6%），且每任务平均只有 2.66 个模型落在距最优 5 分内；单级 task token 在稀疏信号下容易过拟合。KG 家族先验提供"冷启动/跨任务"的粗粒度，task token 提供"细粒度专长"。
- **与现有方案的差异**：不是"32 选 1"的硬路由，而是**两级软路由**：家族级（KG 语义/可供性）+ 任务级（语言）+ 角色/相位级（IP-01-Bi）；任一级置信度低时降级到单专家。
- **技术可行性**：中–高。家族标签来自 IP-09；路由训练可用官方数据的任务/角色标签；置信度用温度校准。
- **所需资源**：数据 = 官方；算力 = 小；接口 = 无。
- **落地步骤**：①用 IP-09 生成家族标签；②训练两级路由 + 置信度；③离线测"家族 oracle / task oracle"的兑现率；④真机 A/B；⑤准备单专家降级形态。
- **风险**：①家族划分 in-sample 乐观（48%–71.5% 是上界）⇒ 必须用留出任务验证；②家族错配 ⇒ 置信度门控 + task token 兜底；③路由错 → 错上加错 ⇒ 低置信退回单专家；④合规 ⇒ 仍是一个 checkpoint。

### IP-01-Bi · RoleToken-MoE（P1）

- **变更**：在 v1 的 `z_task × z_phase` 上增加 `ρ`（角色）与 `c`（耦合）token；专家按"角色-相位"复用（每个专家至少服务 2 个 `(task, role)` 对），任务 token 只做条件化。这样 32 个任务不再需要 32 个专家，而是"持/操作 × 相位"的组合专家。
- **验收**：代理评测 ≥+2.0 分；严格单专家降级损失 ≤1.5 分。
- **风险**：角色标签噪声；合规（单 checkpoint 内多专家）⇒ 先书面确认，准备单专家 + token 形态。

### IP-02-Bi · BiGraspVerify（P0）

- **变更**：`g_t` 从单手扩展为 `(g_L, g_R, p_coupled, slip)`；介入准则升级为"持手未确认 ⇒ 操作手不发力"；不可抓时仍走非抓取原语。
- **验收**：单手/耦合 AUROC ≥0.85；假阳 ≤2%；不降基线。
- **风险**：误判不对称（漏判把可救失败变硬失败）；伪标签漂移；非抓取原语破坏场景。

### IP-03-Bi · BiChunkStitch（P0）

- **变更**：耦合相位 `T_a^L = T_a^R = min(T_a^L, T_a^R)`；缝合目标从"每臂 C0"升级为"相对位姿 `T_rel` 连续 + 耦合残差 `r_c` 连续"；非耦合相位退回独立 chunk。
- **验收**：耦合相位相对位姿跳变 ↓≥50%；成功率不降；0 次 ACTION REJECTED。
- **风险**：评测端可能自带插值/平滑 ⇒ 先用官方 client 复刻语义；短 chunk 增加延迟；过度平滑降成功率。

### IP-06-Bi · BiGraphBench（P0）

- **变更**：八因子 `P(success) ≈ P(reach)·P(grasp|reach)·P(couple|grasp)·P(coordinate|couple)·P(transport)·P(align)·P(insert/place)·P(release)`；`couple` = 双 grasp 确认 + `T_rel` 稳定；`coordinate` = 角色一致的同步；OOD 切分按**物体属性**（可旋转/可插入/可变形/宽度/透明度）而非仅实例。
- **验收**：与真机相关 \|r\| ≥0.5；八因子 bootstrap top-1 一致率 ≥0.8。
- **风险**：代理指标失真；couple/coordinate 标签噪声；OOD 属性切分覆盖不足。

## 4. 符号与定义（U13–U24；U1–U12 继续有效）

| 符号 | 含义 |
|---|---|
| `G_scene` | 场景图：物体实例 + 属性 + 空间/功能关系 |
| `G_aff` | 可供性图（BAG-KG）：类型化节点/边 |
| `s` | 任务模式 schema |
| `P_s, Pre_s, Eff_s` | schema 的子图模板 / 前条件 / 效果 |
| `ρ_s, φ_s, M_s` | schema 的角色模板 / 相位顺序 / 约束流形 |
| `T_L, T_R` | 左右 EE 在基座系的位姿 ∈ SE(3) |
| `T_rel` | 相对位姿 `T_L^{-1} T_R` |
| `r_c` | 耦合残差 `dist(T_rel, M_s)` |
| `c_t` | 耦合状态 ∈ {free, one_hand, coupled, slipping, decoupled} |
| `ρ_t` | 角色 ∈ {L_H R_O, L_O R_H, both_H, both_O, independent} |
| `p_coupled` | 耦合置信度 |
| `z_graph` | 图条件 token（场景图 + schema 的嵌入） |

**定义 U13（场景图）** `G_scene = (V_s, E_s)`，`V_s` 为物体实例节点（带属性向量 `a_v`：刚性/可变形/可旋转/可插入/容器/宽度/透明度/易碎），`E_s` 为带类型的关系边（on/in/near/part-of/occludes/contains）。
**定义 U14（可供性图）** `G_aff = (V_a, E_a)`，节点类型 `V_a = O ∪ A ∪ P ∪ S ∪ Φ ∪ C ∪ R`（物体类别 / 属性 / 动作原语 / schema / 相位 / 约束 / 角色）；边类型 `E_a = {requires, enables, precondition, effect, alternative-to, couples-with, role-template, phase-order}`。
**定义 U15（任务模式）** `s = (P_s, Pre_s, Eff_s, ρ_s, φ_s, M_s)`：`P_s` 是带槽位的子图模板；`Pre_s`/`Eff_s` 是一阶谓词；`ρ_s` 是角色模板；`φ_s` 是相位偏序；`M_s ⊂ SE(3)` 是耦合流形。
**定义 U16（schema 检索）** `s* = argmax_{s∈S} [ Sim(G_scene, P_s) + λ·log P(s|ℓ) ]`；取 top-k 且分数 ≥ `τ_schema`；否则返回通用 schema `s_gen`。
**定义 U17（可执行性 / sound filter）** `Feasible(s, G_scene) = ∧_{p∈Pre_s} p(G_scene)`；不可行时沿 `alternative-to` 边取替代；若 `Pre_s` 中每条都是**必要**条件，则 `Feasible=false ⇒ s` 确实不可行（无误删）。
**定义 U18（相对位姿与耦合流形）** `T_rel = T_L^{-1} T_R`；`M_s`：刚性固定抓取为单点/小邻域；一维关节（瓶盖/钥匙/拉链）为 `{T_rel(θ)}`；可变形为分布。
**定义 U19（耦合残差）** `r_c = dist(T_rel, M_s)`；SE(3) 上用测地距离，或参数空间上 `min_θ ‖T_rel − T_rel(θ)‖`。
**定义 U20（耦合状态）** `c_t ∈ {free, one_hand, coupled, slipping, decoupled}`，转移由 U23 的自动机给出。
**定义 U21（角色）** `ρ_t = argmax_ρ P(ρ | G_scene, ℓ, s*)`，`ρ ∈ {L_H R_O, L_O R_H, both_H, both_O, independent}`；角色可交换，交换前必须过一次 `r_c` 检查。
**定义 U22（相对坐标双臂策略）** 耦合时 `π(a_L, a_R | o, ℓ, s, ρ, c) = (a_H, T_H · π_O(o, a_H))`；非耦合时退回 `π_ind(a_L|o)·π_ind(a_R|o)`；耦合时两臂共享 chunk `T_a`（U8 的双臂扩展）。
**定义 U23（耦合自动机）** 状态 `c_t`，转移守卫：`free → one_hand`（单 grasp `g>τ_g`）；`one_hand → coupled`（双 grasp + `p_coupled>τ_c` + `r_c<τ_r`）；`coupled → slipping`（`r_c` 上升或 `p_coupled` 下降）；`slipping → decoupled`（松手/失败）；`decoupled → free`（重抓）。
**定义 U24（图条件 token）** `z_graph = E_G(G_scene, s*)`；作为软 prompt/FiLM 注入 IP-01-Bi 的路由与动作专家，不改变对外接口。

```python
class BAGBuilder:
    def build(self, episodes, ontology):

        for ep in episodes:
```

```python
# ===== IP-09 + IP-12：检索 + sound filter + 两级路由 =====
class GraphRouter:
    def route(self, obs, lang):
        Gs = self.scene_graph(obs)                          # U13
        cands = self.retriever.topk(Gs, lang, k=5)          # U16
        s = next((c for c in cands if feasible(c, Gs)), None)  # U17
        if s is None or cands[0].score < self.tau_schema:
            return GENERIC_SCHEMA, None                     # 回退
        rho = self.role_head(Gs, lang, s)                   # U21
        z_graph = self.graph_encoder(Gs, s)                 # U24
        return s, (rho, z_graph)
```

```python
# ===== IP-11：耦合确认 =====
class CouplingGuard:
    def estimate(self, obs, schema):
        TL = pose(obs["observation.state.left_ee_pose_gripper_base"][-1])
        TR = pose(obs["observation.state.right_ee_pose_gripper_base"][-1])
        Trel = inv(TL) @ TR                                 # U18
        rc = dist_to_manifold(Trel, schema.M)               # U19
        gL, gR = self.grasp_prob(obs)                       # IP-02-Bi
        feat = cat(self.visual(obs), rc, Trel_vel(Trel), gL, gR)
        p = sigmoid(self.net(feat))                         # p_coupled
        c = self.automaton(p, rc, gL, gR)                   # U20/U23
        return c, p, rc
```

```python
# ===== IP-10：相对坐标双臂策略 =====
class RelFramePolicy:
    def act(self, obs, schema, rho, c):
        if c.state != COUPLED:
            return self.independent(obs, schema, rho)       # 回退
        aH = self.holder_head(obs, rho.holder)              # 低频、准静态
        aO_rel = self.operator_head(obs, rho.operator, aH)  # 高频、相对
```

```python
           "transport", "align", "insert", "release"]
def decompose(ep, labels):

        out[f] = float(ok) if alive else 0.0
```

## 6. 推导（L8–L13）

**引理 L8（耦合降维）** 若物体为刚性且两只手都与其固连，则可行的双臂 EE 动作位于 `6 + d_int` 维流形（物体位姿 + 内部自由度），而非 12 维；约束感知策略的搜索空间维数不高于无约束策略，因此在同样覆盖精度下样本复杂度不劣。若物体可变形/滑动，则 `d_int` 增大，降维收益下降。∎

**引理 L9（时间尺度分离）** 若稳定手速度上界为操作手速度的 `ε` 倍，则 `T_rel` 的一阶动力学主要由操作手决定，稳定手的绝对运动只以 `O(ε)` 进入；因此"稳定手准静态 + 操作手相对"的两时间尺度策略的近似误差为 `O(ε)`。若 `ε` 不小（快速换手/搬运），需退回联合策略。∎

**引理 L10（家族路由捕获上界）** 对任意任务划分 `F`，家族级 oracle 不高于 per-task oracle；teaser 榜 in-sample 测量：`k=5` 捕获 48.0%，`k=7` 捕获 57.0%，`k=12` 捕获 71.5%（均为乐观上界，因为家族划分与模型选择用了同一批数据）。⇒ 粗粒度 KG 先验只能吃一半左右，必须保留细粒度 task token。∎

**引理 L11（sound filter 的安全性）** 若 `Pre_s` 中每条都是**必要**条件（如平行夹爪抓取要求物体宽度 ≤ 开口），则 `Feasible(s)=false ⇒ s` 确实不可行；过滤器不会误删可行方案，只会降低覆盖率（漏掉可行方案）。若前条件只是充分/近似，则 soundness 不成立，必须把图谱限制在硬几何约束上。∎

**引理 L12（耦合介入的不对称代价）** 沿用 L3 的形式：净收益 `= r·Δ_gain − α·Δ_loss − overhead`；但耦合假阳性（以为耦合其实没耦合）的 `Δ_loss` 大于单手抓握假阳性（可能两臂互顶/挤飞物体），故要求 `α ≤ 0.01`，且 `n_retry ≤ 3`；否则退回独立策略。∎

**引理 L13（属性组合泛化的误差界）** 若未见物体被正确映射到属性类 `a`，则策略在未见物体上的误差 `≤ err_attr + max_a err_policy(a)`；KG 只在 `err_attr` 小的时候有帮助。若属性分类错误，图谱会把物体路由到错误 schema，误差反而放大。∎
