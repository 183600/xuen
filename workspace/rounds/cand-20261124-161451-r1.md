## 1. 两个灵感的第一性原理

### 灵感 1 ·「实时控制」→ 迟到即错误：控制核心硬实时，感知只能软实时

**直觉**：实时系统的正确性是二维的——值对，且**按时**。一个晚到的完美动作是错误动作。在本赛里它有两种具体形态：客户端错过截止 → `ACTION REJECTED`；以及步骤分惩罚的「绕远路」。第 3 轮把状态层塞进了执行栈，却从未问过：「加了它之后，还来得及吗？」

**严谨重述**：VLA 策略本质是滚动时域控制器（receding-horizon），action chunk 是时域内的开环段。实时控制给出了三件工具：

- **任务模型 + 截止调度**：把整栈拆成硬实时集 `H={安全、伺服/断言、动作发射}` 与软实时集 `S={状态层更新、检测、介入规划、日志}`；`H` 用固定优先级钉死控制率，`S` 用 EDF / 服务器（server）在剩余预算内跑（U19 / L17）。
- **自触发替代固定低频**：状态层不再每 `N_LOWFREQ` 步盲目更新，而是**预测协方差何时将越过 χ² 门限，恰在越过之前调度下一次更新**（self-triggered control）。负载高时返回粗估计并膨胀 `Σ`。
- **陈旧度 = 不确定度（本轮核心合成）**：状态更新被跳过/迟到 `τ` 步 ⇒ 先验协方差按过程噪声增长 `Σ ← Σ + Qτ`（L14）。把膨胀后的 `Σ` 喂进第 3 轮的 U17 卡方断言，**断言自动变保守**（不确定带变宽、不提前判「到点」），介入自动变谨慎。用**已有数学吸收时序故障**，不新增拍脑袋规则。
- **chunk 视界 H 是实时旋钮**：`H` 大 ⇒ 推理次数少、时延压力小，但扰动平均未被检出时长 ≈`H/2`；由 L15 给出 `H*(D_max, N)`，把「开环段长度」与「扰动反应时延」这一经典控制权衡显式化。
- **退化链新增时间驱动档**：`Level-1.7 = 硬截止压力 → 关停全部软实时感知，用缓存状态 + 膨胀 Σ 跑伺服`。它与第 3 轮 `Level-1.6`（故障驱动）**正交**：一个因模块坏了而降级，一个因时间不够而降级。

### 灵感 2 ·「伦理与合规」→ 安全包络（Simplex）+ 审计账本；合规是硬约束

**直觉**：具身智能的伦理不是论文里的一段话，而是**运行时不变量**：不伤人、不毁物、可审计。经典实时安全工程的答案是 **Simplex 架构**——高能力但未验证的控制器（VLA）只负责「提议」，一个小的、可验证的安全控制器可否决并接管。

**严谨重述**：

- **安全包络 = 控制不变集** `S = {x | h_k(x) ≥ 0}`，`h_k` 为控制屏障函数（CBF）：工作空间边界、关节速度/加速度、自碰撞、**人距**、力矩/电流代理。守卫 `G(x,u)` 否决任何使 `h_k(x') < 0` 的提议动作；回退 `π_safe`∈{刹车、保持、后退} 可验证。若守卫每控制步按时运行、且 `π_safe` 能维持 `S`，则闭环**永不出界，且与策略好坏无关**（L16）。这是「合规即构造」，不是事后过滤。
- **合规的两个具体面**：
  - **数据来源合规**：v3 的 IP-14 依赖外部 `DiverseManip` 做未见物体训练。若手册禁止外部数据/预训练权重，**IP-14 直接不合规**。手册仍不可读（F6）⇒ 本轮必须**先建来源合规矩阵**（每个 IP 标注 官方/外部/合成/无），并对「未知」按「不允许」处理（提交物保守）。这是本轮最不性感却最可能致命的风险。
  - **可审计 / 隐私**：每个 episode 产出**决策账本**（U21：状态估计与 Σ、断言结果与 α、介入、安全否决、动作哈希、数据/模型/配置哈希）。人为干扰回放含人脸 ⇒ 端上处理、不留可识别帧、只留聚合统计。
- **两灵感耦合（本轮中心主张）**：**安全层必须是最高优先级的硬实时任务；迟到的安全检查等于没有安全。** 因此 IP-16（实时调度）与 IP-17（安全包络）是**同一个系统**：调度器保证安全任务 WCET 可调度，安全包络必须便宜到可被调度。IP-15 的「让步（YIELD）」并入统一仲裁：`安全 > 人接触让步 > 正常执行`。

## 2. 研究问题（新增 Q13–Q16，接第 1–3 轮 Q1–Q12）

- **Q15（安全与合规保证）**：Simplex-CBF 守卫能否在 32 项任务上做到**零硬约束违反**且成功率不降？提交物在（仍不可读的）规则下是否来源合规？（E636/E637）
- **Q16（新任务族威胁）**：新语料的**可变形衣物（Fold_Clothes）**与**长程装配（Assemble_Stool）**是否击穿 IP-13 的刚体假设（单一位姿 + 协方差）？（E638）

## 3. 设计原则（新增 P13–P15，接第 1–3 轮 P1–P12）

- **P13（调度即正确性）**：每个模块必须声明 `(优先级, WCET, 截止, 周期)`；硬实时控制核心绝不被软实时感知阻塞；安全任务优先级最高；**超时的结果丢弃而非迟到使用**。
- **P14（不确定度吸收时序故障）**：任何跳过/迟到的状态更新都必须膨胀 `Σ`（默认 `+Qτ`），不得静默复用陈旧状态；系统因此「按构造」变保守，而不是靠额外开关。
- **P15（安全是硬约束、合规可审计）**：安全包络可否决任何 VLA 动作；硬约束永不进入优化目标；每个 episode 产出可审计账本；每个 IP 标注数据来源，提交物只允许落在允许来源内（未知 = 不允许）。

## 5. 本轮最大风险

**安全层对感知的软实时依赖**：CBF 的人距项来自检测器，而检测是软实时的——若守卫信任了陈旧/漏检的人体位置，L16 的「安全保证」会退化为「检测到才安全」的假象。对冲：①人距 CBF 用**膨胀半径** `d_safe + v_max·τ_stale`（把检测时延换成几何裕度）；②保留**感知无关的硬回退**（接触/电流尖峰 → 立即刹车）；③守卫**未在截止内完成即判不安全**（fail-safe，而非 fail-operational）；④E636 用对抗动作 + 脚本化危险注入验证。次要风险：共享 GPU 上 WCET 难界定 → 经验 P99 + 看门狗 + 硬实时核只跑 CPU 侧廉价检查；外部数据合规 → 来源矩阵 + 合规回退，未知按不允许。

## 3. 新增 IP 详述

### IP-17 · SafetyEnvelope（Simplex-CBF 守卫 + π_safe）（P0，新，MVP 门）

- **动机**：合规与安全是**硬约束**，不是优化项；任何逐点过滤都无法保证「永不违反」，而 Simplex 可以（L16）。同时它把「人为干扰让步」与「防毁物」统一成一个可验证机制，比 v3 的规则级 YIELD 更可靠。
- **与现有方案差异**：v3 的 IP-15 是「检测→分类→响应」的启发式；IP-17 是**与策略解耦的运行时安全控制器**。VLA 好坏不影响硬约束成立，只影响成功率。
- **技术可行性**：高。CBF 只需关节/EE 状态与廉价几何/电流检查；感知型人距项用膨胀半径保守化；回退 π_safe 为刹车/保持/后退的有限状态机。
- **资源**：算力=极小（CPU 侧，每控制步 <1 ms 量级）；数据=无；接口=无新增字段（内部否决）。
- **落地步骤**：①定义 CBF 清单 `h_k`（工作空间/速度/加速度/自碰撞/人距/力矩代理）；②实现守卫 `G(x,u)` 与 π_safe；③人距项用 `d_safe + v_max·τ_stale` 膨胀；④接入 IP-16 最高优先级槽；⑤E636 对抗策略 + 危险注入；⑥与 IP-15 仲裁统一（安全 > 接触让步 > 正常）。
- **风险**：感知软实时（最大风险，见 §10）；过度保守吃成功率/步骤分（调裕度、分硬/软两级）；WCET 不稳定（廉价检查 + 看门狗）。

### IP-16 · RT-Stack（EDF + 自触发 + 时间驱动退化）（P0，新，MVP+1）

- **动机**：v3 加入状态层后从未做可调度性分析；感知与控制在共享算力上会互相拖垮。实时控制把「降级」从故障驱动扩为**时间驱动**（L17），并让状态层自触发（省算力且不牺牲精度）。
- **与现有方案差异**：v3 的 `N_LOWFREQ` 是固定常数、`Level-1.6` 只在模块坏时触发；v4 用**马氏超限预测**决定下一次更新时刻，并在硬截止压力下先停软集（Level-1.7）。
- **技术可行性**：高。调度器是工程件（优先级 + 预算 + 看门狗）；自触发只需闭式/查表的协方差预测。
- **资源**：算力=调度开销可忽略；数据=无；接口=无。
- **落地步骤**：①给每模块标注 `(p,C,D,T)`；②实现硬集固定优先级 + 软集 EDF/服务器；③实现 `Σ+Qτ` 膨胀与自触发时刻求解；④接入 IP-09 断言（吃缓存状态）；⑤看门狗与超时丢弃；⑥E634/E635。
- **风险**：共享 GPU 的 WCET 难界定（经验 P99 + 保留预算）；优先级反转（共享检测器用优先级天花板/只读副本）；「自触发」过疏导致漏检（L15 约束 + E635 门槛）。

### IP-18 · ComplianceLedger + 来源合规矩阵（P1，新）

- **动机**：合规需要**可证明**而非「声称」。每个 episode 的决策账本既是规则审计资产，也是 IP-06 失败分解与产品可信度的来源；来源矩阵则把「外部数据」这一隐性违规风险显式化。
- **差异**：v3 只把 AuditLayer 并入 IP-03（工程日志）；v4 提升为**跨栈合规账本**，并加数据来源维度。
- **资源**：存储=每 episode 一条结构化轨迹（压缩后 MB 级）；算力=可忽略。
- **步骤**：①定义 U21 schema；②全栈埋点（状态/断言/介入/否决/动作哈希）；③隐私擦除（可识别帧不外存，只留聚合）；④来源矩阵（官方/外部/合成/无 × 每个 IP）；⑤一键复现（数据/模型/配置哈希）；⑥E637。
- **风险**：账本本身含敏感信息（隐私擦除必须前置）；来源判定依赖尚不可读的规则（未知按不允许，保守）。

## 5. 符号与定义（新增 U19–U21；U1–U18 沿用第 1–3 轮）

- **定义 U19（实时任务模型）**：每模块 `m` 记为 `τ_m=(p_m, C_m, D_m, T_m)`（优先级、最坏执行时间、截止、周期）。硬集 `H={safety_guard, servo_assert, emit_action}`，软集 `S={state_update, detect, intervention_plan, log}`。可调度判据见 L17。
- **定义 U20（安全包络）**：`S = {x | h_k(x) ≥ 0, k=1..K}`，`h_k` 为 CBF：工作空间边界、关节速度/加速度、自碰撞、人距、力矩/电流代理。守卫 `G(x,u)=1 ⇔ h_k(f(x,u))≥0 ∀k`；否则回退 `π_safe∈{BRAKE, HOLD, RETREAT}`。人距项使用膨胀裕度 `D_SAFE + v_max·τ_stale`。
- **定义 U21（决策账本）**：每控制步一条记录 `ℓ_t = (t, x̂_t, Σ_t, assert, α, intervention, safety_veto, action_hash, prov, privacy)`；append-only、不可变；`prov=(dataset_id, model_id, config_hash)`；`privacy` 为擦除后聚合标记。

```python
def control_tick(obs, deadline):
    # 1) 安全永远先跑，且必须在本步截止内完成
    veto = safety_guard(obs, cached_state)          # IP-17
    if veto is not None:
        return fallback(veto)                        # π_safe 接管
    # 2) 断言/伺服吃「缓存状态 + 膨胀 Σ」，不等检测器
    state = cached_state.inflated(now - cached_state.t)
    act = servo_assert(state, obs)                   # IP-09
    # 3) 软集只在剩余预算内、且过了自触发条件才跑
    if slack(deadline) > C_detect and state.trigger(now):
        state_update_async(obs)                      # 写回缓存
    return emit(act)                                 # 超时的软集结果丢弃
```

## 7. 推导（新增引理 L14–L17；L1–L13 沿用第 1–3 轮）

**引理 L14（陈旧度—不确定度膨胀）** 设状态更新周期 `T`、实际滞后 `τ`，过程噪声协方差率 `Q≽0`。若按 `Σ_τ = Σ_0 + Qτ` 喂给 U17，则：(i) 接受域在状态空间按 `√(λ_i(Σ_τ)/λ_i(Σ_0))` 单调扩张，「到点」判定只会更保守、不会更激进；(ii) 只要 `Q` 是真实过程噪声的上界，误判「到点」的概率不超过设计水平 `α`；(iii) 若 `Q` 被低估，保证失效——故 `Q` 必须由 E635 校准。⇒ 时序故障被映射为可解释的几何保守性，而非新增启发式。∎

**引理 L15（视界—反应时延权衡）** 设扰动在 chunk 内均匀到达、检测周期 `N`，则从扰动发生到被响应的期望步数 `E[L] ≈ (H−1)/2 + (N−1)/2`（一阶）。给定允许时延 `D_max`：`H ≤ 2D_max − N + 2`。又 chunk 含扰动的概率 `1−(1−λ)^H` 随 `H` 增，故「延长 chunk 省推理」与「缩短 chunk 快反应」直接冲突；`H*` 由实时预算与 `D_max` 联合定。⇒ v3 的「固定 chunk + 固定低频」应改为由该式实时求解。∎

**引理 L16（Simplex 安全保证）** 若 (i) 守卫每控制步在截止内运行；(ii) 对 `∀x∈S` 与任意提议 `u`，要么 `h(f(x,u))≥0`，要么回退 `π_safe` 使 `x'∈S`；(iii) `S` 在 `π_safe` 下不变；则闭环轨迹对任意 VLA 策略都不离开 `S`。**推论（条件性）**：人距项依赖感知，实际保证要求把检测时延换成裕度 `D_SAFE+v_max·τ_stale`，否则 (ii) 前提不成立——这正是把「感知软实时」转成「几何保守」。∎

**引理 L17（EDF 可调度 + 软集预算）** 硬集在 EDF 下可调度 ⇔ `Σ_{H} C_i/D_i ≤ 1`（`D_i≤T_i`）。软集以服务器预算 `U_S = 1 − Σ_H C_i/D_i` 运行，其排队延迟随 `U_S` 单调增。⇒ 只需为硬集留足预算，软集「能做多少做多少」；`U_S` 不足即触发 Level-1.7，降级有明确阈值。∎
