# 第 51 轮（承接第 50 轮 v14；灵感循环第 2 轮；本轮灵感：人机交互 × ROS） · GroundEdge：共地证书 × ROS 零信任证书平面 × 边缘执行租约（九层架构 v15）

> 承接第 50 轮 v14 CoStride-Distill。v14 用 UCC/HVC/CRM/KDX/LFF 把"共创契约、双足可行、证书引导蒸馏"接进八层栈，并把安全论证写成"蒸馏只损失效率、不损失 soundness"。但它仍隐含三个假设：**H13：交互是离散、单通道、可归属的——机器人只面对一个意图连贯的用户，语义由消息显式携带，机器人"说"与人类"懂"默认一致；H14：运行时是单一信任域里的同步可靠系统——A11 假定 G_exact 在实时预算内完成，消息不丢、时钟一致、节点图静态、第三方包可信；H15：认证单元是"机器人+任务"——部署图的组成、QoS、执行器、参数、包版本只是实现细节，不进入证书语义**。两个灵感词精确命中：**人机交互**打破 H13（真实交互是连续多模态、指称歧义、轮流与混合主动、需要修复与共地，机器人自身行为也是通信通道；人还会过度信任或被解释误导）；**ROS** 打破 H14/H15（ROS 2/DDS 是分布式异步 pub-sub，best-effort 会丢、QoS 可错配、默认执行器不实时、节点可动态增删、时钟可偏、包供应链可被投毒；真正的部署单元是整张节点图+QoS+版本，而非单个算法）。耦合出的核心问题：**共地是否成立必须成为放行前置条件；证书必须能作为签名能力凭证沿 ROS 图流动并在执行器边缘被强制执行；图、传输、交互任一改变都必须让旧证书立即失效**。

## 0. 直觉与动机

**灵感 1（人机交互 → 共地不是输入，而是需要证书的联合状态）**
直觉：v14 把人的话当"意图证据"，却默认机器人对指称和承诺的理解与人类一致。真实 HRI 里最常见的失败不是"没听见"，而是"听见了但理解不同"：用户说"把那个拿过来"，"那个"指哪个？点头是同意还是"继续"？机器人说"我走这边"，人理解为"它会绕开我"还是"它会撞过来"？因此需要把**共地（common ground）**显式建模为联合状态，并用可观测证据（回指确认、澄清回答、执行后效、注视/手势/停顿）给出**校准过的共地证书**；共地不足时，机器人只能澄清、示范或执行无承诺后果的动作。
严谨定义见定义 87。核心不是"让 LLM 更自信"，而是"让放行依赖可被统计校准的共地证据"。

**灵感 2（人机交互 → 混合主动权是带租约的控制权，不是隐含礼貌）**
直觉：安全关键系统里"谁现在说了算"不能靠默契。人机混合主动需要显式**主动权租约**：当前 holder、作用域、过期时间、抢占与交还条件；交接期间机器人必须停留在一个已认证的安全不变式里，人类接管必须在有界时间内完成，否则机器人执行 CRM。否则会出现"人以为机器人在听、机器人以为人在授权"的权威混淆。
严谨定义见定义 88。租约把"礼貌的轮流"变成可检查的单写者协议。

**灵感 3（ROS → 大脑不可信，守卫必须下移到执行器边缘）**
直觉：v14 的 G_exact 默认在"大脑"里运行；但 ROS 图里任何上游节点都可能崩溃、被替换、被投毒或 QoS 错配。安全的正确位置不是在提议者旁边，而是在**执行器最后一道门**：一个最小、确定性、可单独认证的 Safety Enforcement Node（SEN）坐在 `ros2_control` 硬件接口前，只认**签名执行租约**；租约过期、版本/图哈希不匹配、看门狗异常，就在本地钳制到 CRM。这样"大脑被攻破"最多导致租约被拒/回退，而不是危险动作被执行。
严谨定义见定义 91–92。"守卫在边缘，不在大脑"是本轮最重要的架构位移。

**灵感 4（ROS → 证书要会走路：签名信封、图钉与传输感知时间预算）**
直觉：证书若只是某进程内存里的布尔值，跨节点就不可信。证书必须封装成**签名信封**，携带内容摘要、契约版本、部署图哈希、签发者、epoch、nonce、签发/截止时间；任何节点可独立验证而不必信任发送者。更进一步，证书只在**被钉住的部署图**（节点、话题、QoS、参数、包版本、执行器、时钟）下有效；节点增删、参数/QoS 改动、包升级都产生新图 epoch，旧证书 fail-closed。时间上必须做**端到端预算传播**：证书 TTL 要覆盖 P99.9 延迟+抖动+余量，否则"逻辑正确但到达已过期"就是不安全。
严谨定义见定义 90–93。图与传输不是实现细节，而是证书语义的一部分。

**灵感 5（耦合 → 从"意图到力矩"的证书连续统；交互蒸馏只学提议与表达，不学评估与放行）**
直觉：把上面四件事接起来，安全不再是"某个模块的属性"，而是一条**从人类共地 → 意图/契约 → 可行性 → 签名信封 → 边缘租约 → 力矩**的证书连续统。交互蒸馏（IXD）可以让 student 学会"何时澄清、如何用可读动作/解释建立共地"，但共地证书的校准、G_exact 的求值、SEN 的放行永远不蒸馏——学生只影响"问不问/怎么表达/走哪条路径"，不影响"能不能动"。
严谨定义见定义 94–96。这把 v14 的"只近似搜索"的不对称，扩展成"只近似提议与表达"，但把新的信任锚暴露得更清楚。

**耦合升级**：v14 八层之上新增 **L0 分布式底座与执行边（SROS2 enclave / 图钉清单 / CE / SEN / AL / TBC）**，L2.5 升级为**交互共地与共创契约层（IGC + CRP + ILM + XTC + UCC）**。九层 v15：根信任+能力格 + L0 分布式底座与执行边 + L1 几何感知 + L2 任务/上下文/记忆/语音 + L2.5 交互共地与共创契约 + L3 关节证书/抽象/决策 + L3.5 动力可行（HVC/CRM）+ L4 CAR/Shield/CBG+/KDX + L5 DCL/真机/HCI 评测 + L6 原型证伪/XFER/LFF/IXD。JCPS 输出扩为 `(v,a,m,q,ι,κ,g,λ)`（g=共地状态，λ=执行租约/主动权句柄）。

## 1. 形式化定义（增量：定义 87–96）

**定义 87（交互任务、共地状态与共地证书）**
交互任务 `I=(O,R,Π)`：O 为指称/对象集合，R 为角色，Π 为轮次/协议模板。共地状态 `g=(a_sh,β_ref,q_turn,ι_init,S_commit,m_hist)`：共享注意、指称绑定分布、轮次相位、主动权持有者、承诺栈、多模态历史。共地证书 `B_g: G×Π→[0,1]` 满足
`B_g(g,π) ≥ 1−α_ground ⇒ P(referent/intent 与人类实际一致 | π 记录的共地证据) ≥ 1−α_ground`。
`B_g` 只能由可观测证据更新（回指确认、澄清回答、执行后效、注视/手势/停顿），并用 conformal/置信区间校准；**禁止用未校准的 LLM 置信度或语音识别置信度冒充共地证书**。放行规则：`B_g<θ_ground` 时只允许澄清/示范/指称确认/无承诺后果的最小动作。

**定义 88（混合主动权租约）**
`IL=(holder,scope,T_expire,preempt,handback,Z_hold)`，holder∈{robot,human,shared}；scope 为可控制的动作/参数子集。单一写者：同一时刻至多一个 holder 对 scope 内动作有写权；他人命令是 proposal。交接约束：`z(t)∈Z_hold`（已认证安全不变式）直到 handback 被确认；人类接管须在 `τ_take` 内完成，否则机器人执行 CRM。交接/抢占事件全部入账。

**定义 89（解释保真与信任校准）**
解释 `E` 必须携带其引用的证书摘要与裕量。保真条件：`E` 不得声称比实际 `B/B_v/AL` 更大的安全裕量；`α_expl` 为"解释误导安全裕量"的概率。信任校准：用红队"不安全建议"测人类顺从率；若过度信任超过阈值，系统必须降级自主权、改变解释粒度或强制确认，而不能利用人的信任。

**定义 90（ROS 部署图与图钉证书）**
部署图 `G_R=(N,T,Q,Θ,V,X,C)`：节点、话题/动作、QoS、参数、包/镜像版本、执行器/调度、时钟源。图哈希 `h_G`。证书 `C` 仅在 `h_G(C)=h_G(current) ∧ enclave/访问策略匹配 ∧ 包签名/SBOM 通过` 时有效。节点加入/退出、参数或 QoS 改动、包升级 → 新 graph epoch；旧证书一律 fail-closed，必须重认证。

**定义 91（证书信封）**
`CE=(payload,digest(C),h(κ_c),h_G,issuer,epoch,nonce,t_issue,t_deadline)`，由签发者签名。任何节点仅凭公钥/策略即可验证，无需信任发送者；epoch/nonce 防重放，`t_deadline` 防过期，`h_G` 防跨图搬运，`h(κ_c)` 防旧契约复用。

**定义 92（执行租约与边缘守卫）**
`AL=(id,holder,CE_digests,scope,t_expire,mrc_fallback,energy_cap)`。SEN 是位于 `ros2_control` 硬件接口前的最小确定性节点：**唯一**能授权执行器写入的组件；每条运动命令必须携带有效 AL；任一检查失败（签名/版本/图哈希/期限/看门狗/liveliness）即本地钳制到已认证 CRM。属性：无租约不执行、单写者、权限上界、故障局部化。

**定义 93（传输感知时间预算）**
端到端最坏延迟 `L_WC=Σ_i(C_i+J_i+Q_i)+D_QoS`；证书有效期须满足 `TTL ≥ L_WC+P99.9 抖动+τ_margin`；时间戳在 `/clock` 下单调，仿真/墙钟切换须显式标注。**时间健全性**：`t_deadline > t_issue+L_WC+τ_margin`，否则证书即使内容正确也不得放行。

**定义 94（交互蒸馏）**
teacher `𝒯` 含人类模型与交互策略；student `s_φ:(o,ctx,g)→(候选动作, 表达/可读动作, 澄清选择, 交接建议)`。训练数据 = teacher rollout + HRI 研究/真机交互日志 + 共地失败样本；损失 = 任务项 + 共地裕量回归 + 可读性/修复成功率 + 校准惩罚。**共地证书校准、G_exact 求值、SEN 放行不可蒸馏**；学生误差只提高澄清率/回退率，不降低 `θ_ground` 与边缘放行标准。

**定义 95（版本四元组与再认证）**
守卫检查携带 `(h(κ_c),h_G,v_student,v_interaction)` 四元组；任一不匹配 fail-closed。契约、图、学生、交互策略任一变更 → 重解→重蒸馏→再认证（守卫集零违例 + held-out 场景回归 + 图重放通过）方可服役。

**定义 96（账本与十源归因）**
`CCL+++` 在 `CCL++` 上追加：共地/修复/澄清事件、主动权交接、解释-信任事件、图 epoch 变更、SEN 干预/租约拒绝、传输 deadline miss。DDA 归因扩为**十源**：感知/关节/边界/意图/接触/传输/动力/蒸馏/**交互（共地·主动权·解释）**/**底座（图·QoS·执行器·供应链）**。任一来源的置信折损显式入账并参与抽象、速度缩放与自主权缩放，不得静默吸收。

## 2. 新增产出与既有 IP 升级

**IP-91 IGC（Interaction Grounding Certificate）**：校准共地证书 + 修复/澄清策略 CRP；共地不足只许澄清/示范/最小动作。
**IP-92 ILM（Initiative Lease Manager）**：混合主动权租约、单写者、安全交接与有界接管；权威混淆拦截。
**IP-93 XTC（eXplanation fidelity & Trust Calibration）**：解释保真证书 + 过度信任监测与降权。
**IP-94 GPC（Graph-Pinned Certificate）**：部署图清单/哈希、SROS2 enclave、SBOM/包签名；图变更即失效重认证。
**IP-95 SEN（Safety Enforcement Node）**：执行器边缘唯一放行点 + AL 执行租约 + 本地 CRM 钳制 + 看门狗。
**IP-96 CE（Certificate Envelope）**：签名、deadline、epoch/nonce、图/契约版本绑定的零信任证书信封。
**IP-97 TBC（Transport-aware Budget Calculus）**：QoS 感知的端到端延迟/抖动/丢失预算与证书 TTL 推导。
**IP-98 IXD（Interaction eXperience Distillation）**：交互蒸馏；只学提议/表达/澄清，不学评估与放行。

**既有 IP 升级**
IP-82 IPC：协议状态并入共地/修复/交接转换；确认信号升级为共地证据。
IP-80 SIG：意图后验并入 `B_g` 与主动权状态 `b'(θ)∝b(θ)·(1+ω_u·c_θ)·1[B_g≥θ_ground]`；硬下界不动。
IP-79 SIC：联合状态扩为 `z=(x_r,x_h,x_e,κ,g,λ)`；屏障条件含共地与租约。
IP-85 MRC：新增"租约过期/边缘看门狗/传输超时"触发；CRM 作为 SEN 本地默认。
IP-83 PFV：场景阶梯加入指称歧义、多用户、口音/噪声、交接抖动、QoS 降级、时钟偏移、节点崩溃。
IP-84 XFER：δ 增"图差异/传输差异/交互人群差异"三维；跨图/跨人群迁移显式膨胀。
IP-77 DDA：八源 → 十源（+交互、+底座）。
IP-61 DCL：采集共地失败、澄清结果、接管、解释-顺从、SEN 拒绝、图 epoch 变更、deadline miss。
IP-62 CCA：新增指称欺骗、权威混淆、过度信任诱导、重放/跨图搬运、QoS 降级、节点冒充、供应链投毒红队。
IP-51 CAR：守卫加"信封验证 ∧ 图哈希 ∧ 租约 ∧ 时间健全 ∧ 解释保真"。
IP-45 总线：新增 grounding-state / initiative-lease / graph-epoch / certificate-envelope / actuation-lease / explanation 话题。
IP-66/67/68：语音/手势进入共地证据；记忆存图与契约版本史；SAB 对交接/共创走双签署。
IP-75 ASC：抽象可行性加入 `g` 与 `h_G`；共地不足或跨图时强制细化/重认证。
IP-74 HTD-Cert：分解节点含交互子任务（澄清/示范/交接）与图约束节点。
IP-72 RRP：e-process 纳入共地/主动权/传输/图证据。
IP-76 CCL：升级为 CCL+++（定义 96），只追加。

## 3. 算法骨架

每个宏周期：
1. **底座自检**：验证 SROS2 enclave、图清单 `h_G`、包签名/SBOM、SEN 自检与看门狗；任一失败 → fail-closed/hold。
2. 读目标、证书、租约、`CCL+++`、四元组版本；不匹配即拒绝。
3. HTD-Cert 展开/复用 DAG；前沿标注交互子任务（澄清/示范/交接）与图约束。
4. **共地更新**：多模态证据更新 `b_g`，计算 `B_g`；`B_g<θ_ground` → 澄清/示范/指称确认/最小动作，禁止有承诺后果的执行。
5. **主动权**：申请/续租 IL；human-held 时机器人只做安全保持与提议；交接期间维持 `Z_hold`，超 `τ_take` 执行 CRM。
6. 意图与协议更新：`b'(θ)` 并入共地与已签承诺；σ 低于阈值只保留 primitive/CRM。
7. KDX 提议-处置：student 提议 `(u_r,a,m,q,ι,κ,g,λ)` + 表达/澄清；`G_exact` 精确求值 B/B_v/PFL/Inv/契约/图哈希/IL/解释保真/时间预算；不通过则更多候选→限量搜索→CRM。
8. 签发 CE 与 AL（含 TTL、epoch、nonce、scope）；只有 SEN 能在边缘验证并授权执行器。
9. 执行中：SEN 监控 deadline/liveliness/看门狗/租约期限；任一失败本地钳制 CRM 并入账。
10. 解释与信任：输出与证书裕量一致的解释；监测过度信任，超阈值则降自主权/强制确认。
11. 若实测违反或共地失败/租约拒绝/传输超时：DDA 十源归因，选最早安全点重共地/修复/重分解/重认证；必要时 CRM。
12. 离线/并行：PFV+LFF 证伪（含 HRI/ROS 故障注入），XFER 估计 δ，IXD 共蒸馏 student（不蒸馏评估）；新反例回灌 DCL/CCA。
13. 所有路径不可行 → 技能合成/人工接管/保护姿态/fail-closed，绝不绕过 SEN、G_exact、L3.5。

## 4. 本轮最大风险

**一句话**：v15 把安全从"大脑里的证书"改写成"沿 ROS 图流动、在边缘执行的证书连续统"，代价是引入了一个新的最小可信基（SEN+签名+图钉+共地校准）——一旦 SEN 被绕过/配置错误、图钉过期仍被放行、或共地证书在人群/语言/噪声分布漂移下失去校准，系统就会变成"签名齐全但语义错误/执行放行"的分布式假安全；因此 SEN 必须最小化并单独认证、密钥与 enclave 必须受保护、图/传输/共地任一不匹配必须 fail-closed 且持续用红队与在线校准证伪。

# 第 51 轮产物 · 创新点清单 v28：GroundEdge（IGC × ILM × XTC × GPC × SEN × CE × TBC × IXD）× 共地证书、ROS 零信任证书平面与边缘执行租约（九层架构 v15）

## 2. 关键算法 伪代码

### IP-91 IGC + CRP（共地与修复）
```
def calibrated_Bg(g, evidence):
    # conformal / 区间校准；禁止裸 LLM/ASR 置信度
    return lower_bound(alignment_posterior(g, evidence), alpha=ALPHA_GROUND)

def repair_or_act(g, plan, evidence):
    bg = calibrated_Bg(g, evidence)
    if bg < THETA_GROUND:
        q = choose_referent_query(g, expected_info_gain=True)
        ledger_append_plus(now(), 'grounding_gap', g, bg)
        return ('clarify', q)                      # 或 demonstrate / minimal
    return ('act', plan)

def minimal_commitment_free(action):
    # 无承诺后果：不移动共享对象、不进入人身邻域、可立即撤销
    if touches_shared_object(action) or enters_personal_space(action):
        return ('hold', explain('need_grounding'))
    return action
```

### IP-92 ILM（混合主动权）
```
def acquire_or_renew_initiative(holder, scope, now, z):
    if not single_writer_free(scope, holder):
        return ('reject', 'authority_conflict')
    if holder == 'human' and not in_certified_hold(z, scope):
        return ('reject', 'unsafe_handoff_state')  # 先回 Z_hold 再交接
    il = Lease(holder, scope, T_expire=now + TAU_LEASE,
               preempt=preempt_policy(scope),
               handback=handback_cond(scope),
               Z_hold=certified_hold_set(scope))
    ledger_append_plus(now, 'initiative_lease', il)
    return ('accept', il)

def enforce_takeover(il, now):
    if il.holder == 'human' and now > il.T_expire:
        return ('crm', 'takeover_timeout')
    return ('continue', il)
```

### IP-94 GPC（图钉）
```
def graph_epoch(nodes, topics, qos, params, versions, clocks, enclaves):
    return H(canonical(nodes, topics, qos, params, versions, clocks, enclaves))

def cert_valid(cert, graph, now):
    return (cert.hG == graph_epoch(*graph)
            and cert.hkappa == contract_hash()
            and now < cert.t_deadline
            and verify_sig(cert)
            and sbom_ok(graph.versions)
            and enclave_ok(graph.enclaves))
```

### IP-96 CE + IP-97 TBC（信封与时间预算）
```
def issue_envelope(payload, cert, graph, now):
    L_wc = sum(node.cost + node.jitter + node.queue for node in graph.path)
    L_wc += qos_drop_delay(graph.qos)
    t_deadline = now + L_wc + P999_JITTER + TAU_MARGIN
    ce = Envelope(payload, digest(cert), contract_hash(), graph_epoch(*graph),
                  issuer=SIGNER_ID, epoch=CURRENT_EPOCH,
                  nonce=fresh_nonce(), t_issue=now, t_deadline=t_deadline)
    return sign(ce)

def temporal_sound(ce, graph):
    return ce.t_deadline > ce.t_issue + worst_case_latency(graph) + TAU_MARGIN
```

### IP-95 SEN（边缘执行守卫）
```
def sen_step(cmd, env, now):
    # 位于 ros2_control 硬件接口前；整个系统中唯一执行器写权限
    if not verify_envelope(cmd.ce, env.pubkeys, env.graph_hash, now):
        return clamp_to_crm('bad_envelope_or_graph')
    if cmd.al is None or cmd.al.t_expire < now:
        return clamp_to_crm('no_valid_lease')
    if not al_matches(cmd.al, cmd, holder_scope=True, energy_cap=True):
        return clamp_to_crm('lease_scope_violation')
    if not env.watchdog_ok or not env.deadline_ok or not env.liveliness_ok:
        return clamp_to_crm('edge_watchdog')
    return actuator_write(cmd.u)                   # 唯一写点
    # 任何上游节点崩溃/被投毒/QoS 错配 → 至多租约被拒，不能绕过 SEN
```

### IP-98 IXD（交互蒸馏，不蒸馏评估）
```
def ix_distill(teacher, student, hri_logs, failures):
    data = teacher.rollouts() + hri_logs + failures
    labels = [(s, teacher.best_action(s), teacher.signaling(s),
               teacher.clarify_choice(s), teacher.margin(s)) for s in data]
    student.fit(labels, loss='task + margin_reg + legibility + repair + calibration')
    # 不训练：B_g 校准器、G_exact、SEN；学生无放行权
    return student
```

### IP-73 JCPS（v15：共地-图钉-边缘租约联合调度）
```
def ground_edge_schedule(goal, certs, leases, graph, b, g, now):
    if not base_selfcheck(graph, now):             # enclave/SBOM/SEN
        return ('fail_closed', 'substrate')
    hg, hk = graph_epoch(*graph), contract_hash()
    bg = calibrated_Bg(g, history(g))
    if bg < THETA_GROUND:
        return repair_or_act(g, plan=minimal(goal), evidence=history(g))
    il = acquire_or_renew_initiative(current_holder(), scope_of(goal), now, current_z())
    if il[0] == 'reject':
        return ('hold_and_propose', certified_hold_set(scope_of(goal)))
    if il[1].holder == 'human':
        return ('hold_and_propose', il[1].Z_hold, propose_only(goal))
    dag = htd_cert(goal, certs, contracts, leases, graph)  # 含交互/图约束节点
    if dag is None:
        return ('synthesize_or_fail_closed', None)
    if not viability_ok(current_z(), current_mode(), contract):
        return ('crm', sen_local_crm())
    for cand in student.propose(o, ctx, g):        # 动作 + 表达 + 澄清
        if not guard.exact_check(cand, hk, hg, il[1], now):
            continue
        ce = issue_envelope(cand, cert_of(cand), graph, now)
        if not temporal_sound(ce, graph):
            continue
        al = issue_actuation_lease(ce, il[1], now)
        return ('actuate', ce, al)
    if full_search_fallback() is not None:
        return fallback
    return ('crm', sen_local_crm())
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| IGC/CRP | O(|evidence|) 更新，O(1) 查询 | O(|history|) | conformal 校准；B_g<θ 时禁止有承诺后果动作 |
| ILM | O(1) 租约操作 | O(1) | 单写者；交接保持 Z_hold；超时 CRM |
| GPC | O(|graph|) epoch，O(1) 比较 | O(|graph|) | 图/QoS/参数/版本任一变更 → 旧证书失效 |
| CE | O(1) 验签/校验 | O(1) | 重放/过期/跨图/旧契约一律拒绝 |
| SEN | O(1)/命令，≤τ_sen | O(1) | 无租约不执行；唯一写点；本地 CRM 兜底 |
| TBC | O(|graph.path|) 预算，O(1) 检查 | O(1) | TTL > 最坏延迟+抖动+余量；不满足不放行 |
| IXD | 学生 O(1) 推理 | O(参数) | 无放行权；误差→澄清/回退，非安全项 |
| G_exact | 承接 v14，≤τ_g | O(1) | 精确求值 + 四元组匹配 + 时间健全 |

**正确性定理（GroundEdge：共地-图钉-边缘复合 soundness）**
假设：(A1)–(A12) 承接 v14（契约 sound、CBG 边界蕴含、租约、初始证书、CCL 只追加、意图支撑覆盖、δ 膨胀、MRC/CRM 可达、`C_cert` 内近似、捕获概率、G_exact 成本认证、共创契约合法）；新增 **(A13)** 共地证书在可交换性/分布假设下校准：`B_g≥1−α_ground ⇒ 对齐概率≥1−α_ground`，且 `B_g<θ_ground` 时不执行有承诺后果动作；**(A14)** SEN 是唯一执行器写点，代码最小且单独认证，本地 CRM 在认证扰动集内 sound，看门狗/期限/liveliness 检查不可绕过；**(A15)** 部署图与认证图一致（`h_G` 匹配）、SROS2 访问控制阻止未授权节点发布执行话题、包签名/SBOM 有效、证书 TTL 覆盖最坏端到端延迟+抖动+余量、时钟偏移有界；**(A16)** 主动权租约单写者、交接保持 `Z_hold`、人类接管在 `τ_take` 内完成或转 CRM、过度信任被 XTC 抑制或降自主权。则沿路径、交互序列、步态相位与图 epoch，
`P(∀t≤T: z(t)∈Z_safe) ≥ 1 − Σ_i α_i − Σ_i ε_hand,i − α_lease − α_intent − α_user − α_viable − α_cap − Σ_ℓ δ_{ℓ→d} − α_ground − α_expl − α_take − α_graph − α_comm − α_sen`；
且**蒸馏仍不进入安全上界**：student 误差只能提高澄清率/回退率 `r_fb`，因为执行要求 `G_exact` 精确求值 + `SEN` 边缘放行；**共地/图/传输任一不匹配均 fail-closed**，共创条款仍只经"能力格 ∧ 可行性剪辑"进入约束。

**关键推论（故障局部化）**：在 (A14)+(A15) 下，任何上游 ROS 节点崩溃、被投毒、参数/QoS 错配或 AI 栈发散，**至多导致租约被拒/回退/CRM（可用性损失），不能导致未认证动作被执行**。这把 v14 的"整栈可信"收缩为"SEN+密钥+图清单可信"；新的 TCB 更小，但仍是新的信任锚，其代码正确性、密钥保管、SBOM 新鲜度、共地校准的人群泛化性均不在定理覆盖内。

## 6. 本轮最大风险

**一句话**：GroundEdge 把安全论证的承重点从"求值是否够快"转移到了"新的最小可信基是否真的可信"——SEN 一旦可被旁路、密钥/图清单一旦失守、或共地证书在真实人群分布上失去校准，整条"签名齐全、边缘放行"的证书连续统就会变成分布式假安全；因此必须把 SEN 压到最小并单独认证、把密钥与图清单纳入受保护根、把共地校准做成在线可证伪的统计承诺，并对图/传输/共地任一不匹配坚持 fail-closed。
