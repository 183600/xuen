# 第 47 轮（承接第 46 轮 v23；本轮灵感：服务设计 × 基线复现） · Service-Blueprint-Repro：服务蓝图驱动的可复现 SLA 证书与基线回归（五层架构 v11）

> 承接第 45 轮 v10（Energy-Context-Depth）与第 46 轮 v23（MVR/VAD/SAB）。此前所有工作都在「组件层」堆证书：姿态证书 P_t、能量租约 ℓ_e、记忆-语音-安全绑定 B(v,P_t)——它们共享两个未被检验的隐含假设：**H5：服务层保证 = 组件证书之和**（组件 sound 即用户感知的可靠服务），**H6：证书的 soundness 可以「一次验证、永久成立」**。两个灵感词精确击穿这两条假设。**服务设计**指出：用户只在前台触点感知服务，后台 fail-closed 不等于可接受体验；真正要交付的是一份服务级协议（SLA），且失败必须走「服务恢复」而非静默降级；前台-后台-失败点构成服务蓝图，任何未映射到触点的后台失败都会变成体验黑洞。**基线复现**指出：服务运行在非平稳分布上，若没有一份可复现的基线，所有 soundness 声明既不可证伪也不可比，且随分布漂移会给出「复现得了旧指标、却已失配现场」的假信心。两者耦合出新问题：**如何把组件证书聚合为一份既可复现、又在前台诚实可恢复的服务级 SLA 证书，同时防止「保可用性」的体验压力悄悄绕过 fail-closed、防止基线冻结在旧分布上提供虚假的通过结论**。

## 0. 直觉与动机

**灵感 1（服务设计 → 服务蓝图与失败点显式化）**
直觉：机器人对用户的「服务」发生在前台触点（语音发起、手势指向、任务进度播报、失败告知），而后台的 PSE/CAR/ECPS/MVR/SAB 用户看不见。今天一次 CAR fail-closed 会把整个交互直接掐断——这就是一个未被设计的失败点。做法：把系统编译成服务蓝图 BP=(前台触点 Φ、后台组件 Ψ、可视分界线、交互分界线、失败点 FP、恢复迁移 TR)，每个后台证书失败必须绑定一个前台恢复动作（诚实告知 + 排队/降级/转人工），不允许无触点的静默失败。

**灵感 2（基线复现 → 服务级契约的可复现性与漂移再基线）**
直觉：一个「姿态证书覆盖 ≥ 1-α_p」的声明，只有在固定场景分布、固定协议、固定随机种子下能被第三方复现，才算科学有效。服务是非平稳的（新物体、新指令、新光照、电池老化），所以基线不能一冻了之。做法：定义可复现基线 β=(D_base, 协议 π, 种子集 Σ, 标定集 C, 容差 ε, 参考指标 m_ref)，并定义复现算子 R_β；要求系统能按需产出「复现证书」证明现场指标与基线在 ε 内一致；同时用两样本检验/支持集覆盖检测漂移 δ_t，触发再基线而非静默沿用。

**灵感 3（耦合 → SLA 证书作为组件证书的「契约聚合」）**
直觉：SLA 不是新传感器，而是一层「聚合与翻译」。定义服务级向量 SLA=(可用性 A、响应时延 L、安全违例率 V、恢复时延 T_rec、披露诚实度 C_trans)，每一维阈值由组件证书经并集界/割集推导而来：某一维失效 ⇔ 存在一条由失败点串联的割集使该 SLO 被破坏。于是 CAR/ECPS 的组件决策必须「向上投影」为 SLA 状态，前台据此决定播报什么、后台据此决定是否降级。恢复动作本身也要证书化（恢复不得违反安全证书、不得谎报），否则服务设计会被安全证书反噬。

**耦合升级（五层 v11）**：在 v10 四层之上新增 **L_svc 服务契约层**。SBB 编译服务蓝图并标注失败点；SLA-CERT 把组件证书聚合/分解为服务级证书并把失败点映射到恢复动作；BRR 维护可复现基线 β、按需复现、检测漂移并驱动再基线。上层：CAR 守卫向外暴露服务状态与服务恢复转移；MVR 记忆条目携带基线出处；CCA 新增「体验压力绕过 fail-closed」与「基线博弈」红队；DCL 采集维持基线支持集覆盖的样本；总线新增服务级话题。

## 1. 形式化定义（增量：定义 59–63）

**定义 59（机器人服务蓝图）**
BP=(Φ, Ψ, L_vis, L_int, FP, TR)。Φ 为前台触点集合（语音发起/手势指向/进度播报/失败告知）；Ψ 为后台组件（PSE, CAR, ECPS, MVR, SAB…）。失败点 FP={(u, ψ, C_ψ) : 触点 u 暴露后台组件 ψ 的证书 C_ψ 失效}。恢复迁移 TR: FP → 恢复动作。
**蓝图完备性**：∀ψ∈Ψ，若 C_ψ 可能失败，则存在 u∈Φ 使 (u,ψ,C_ψ)∈FP 且 |TR(·)|≥1，即无「无触点的静默失败」。

**定义 60（服务级 SLA 与 SLA 证书）**
SLA 向量 SLA=(A, L, V, T_rec, C_trans)，阈值 θ_svc=(θ_A, θ_L, θ_V, θ_rec, θ_trans)。SLA 证书在时域 H 上：
`P(∀s∈{A,L,V,T_rec,C_trans}: s 满足 θ_svc 于 H) ≥ 1-α_s`。
**组件聚合（并集界）**：设组件证书覆盖数为 k，各失败概率 ≤ α_i，则 `α_s ≤ Σ_i α_i`。
**割集判据**：服务 SLO 被破坏 ⇔ 存在失败点割集 K⊆FP 使 k 条证书同时失效。

**定义 61（可复现基线）**
基线 β=(D_base, π, Σ, C, ε, m_ref)。复现算子 R_β(S) 在协议 π、种子 s∈Σ、标定 C 下跑系统 S 得指标 m。
**可复现判据**：`d(m, m_ref) ≤ ε` 在显著水平 γ 下成立。
**样本复杂度**：要把 ±ε 以置信 1-γ 认证，独立回合数 `n ≥ O(σ²·log(1/γ)/ε²)`。

**定义 62（基线漂移与再基线）**
漂移 `δ_t = D_f(P_live, D_base)`（两样本 MMD/卡方）。**支持集覆盖** `cov = P_live(X∈supp(D_base))`。
**再基线触发**：δ_t > δ_max 或 cov < cov_min；触发后冻结旧 β、以 D_live 重建 β' 前，所有依赖搬移基线的 SLO 声明标注为「待复现」。
**漂移 soundness**：不得在 δ_t 超阈时继续宣称「已复现」。

**定义 63（服务恢复策略与恢复证书）**
恢复策略 ρ: f∈FP_state → (降级模态 m_deg, 前台披露 msg, 队列 Q_safe, 升级 escalate)。
**恢复证书 Rec-Cert**：`P(安全证书在恢复中不被违反) ≥ 1-α_rec` 且 `T_rec ≤ θ_rec` 且披露诚实 `‖msg - 真实状态‖ ≤ η`。
**诚实性**：不得以「正在处理」掩盖 fail-closed。

## 2. 三大新增产出与既有 IP 升级

**IP-69 SBB（Service Blueprint Binder）**
- 服务蓝图自动编译：从组件证书导出前台触点与失败点
- 失败点-恢复动作绑定：每个组件失败映射到降级/排队/披露
- 可视/交互分界线：区分用户可见状态与后台证书状态
- 蓝图完备性检查：发现无触点的静默失败并报错

**IP-70 SLA-CERT（Service-Level Agreement Certificate）**
- 组件→服务聚合：并集界给 α_s，割集定位破坏源
- 服务级契约监控：A/L/V/T_rec/C_trans 五维实时评估
- 失败点割集分析：定位哪些组件组合能击穿 SLO
- 前台诚实度预算：披露信息与实际状态的偏差上界

**IP-71 BRR（Baseline Reproducer & Regression）**
- 可复现协议执行：固定 D_base/π/Σ/C，按需产出复现证书
- 统计复现判定：d(m,m_ref)≤ε 的假设检验，输出置信
- 漂移检测与再基线：两样本检验 + 支持集覆盖，驱动 β'
- 基线回归门禁：CI 化，阻止性能回退合并

**既有 IP 升级**
IP-51 CAR：守卫暴露服务级状态，fail-closed 必须附带 Rec-Cert，禁止无披露停机
IP-63 ECPS：效用函数在安全约束下加入服务可用性项，但可用性不得覆盖安全硬约束
IP-66 MVR：记忆条目携带基线出处 β_i，跨基线版本记忆按标签失效
IP-61 DCL：采集任务以「维持基线支持集覆盖」为目标
IP-62 CCA：新增体验压力红队（催促绕过排队）、基线博弈红队（过拟合旧分布）
IP-45 总线：新增 service-state / sla-cert / baseline-drift / recovery-action 话题

## 3. 算法骨架

服务契约层每控制周期：
1. 读后台证书状态 {C_ψ}、触点在途请求、当前基线 β、现场分布统计
2. SLA-CERT 聚合 α_s，逐维评估 A/L/V/T_rec/C_trans，做割集分析
3. 若某 SLO 逼近阈 → 触发对应失败点 FP 的恢复迁移 TR
4. SBB 校验：本次失败是否有前台触点承接；无则升级为蓝图错误并告警
5. BRR 计算 δ_t 与 cov；超阈则标注「待复现」，按 E118 调度再基线
6. 任意安全证书失效 → fail-closed 必须同时产出 Rec-Cert（降级+披露+排队）
7. 服务可用性项仅在安全硬约束可行域内参与 ECPS 效用，不得反向放松 CAR

## 4. 本轮最大风险

**一句话**：服务设计带来的「保可用性/保体验」压力会与 fail-closed 直接冲突——若允许为维持 SLA 的响应时延而缩短甚至跳过排队与披露，组件层的安全证书就会被体验目标悄悄架空，恢复动作沦为表演；同时基线复现若只比对指标而不管支持集覆盖，系统会「漂亮地复现」一份早已失配现场的旧分布，给出虚假通过结论，因此必须把安全硬约束置于 SLA 之上、把恢复纳入证书化、并以支持集覆盖而非仅指标一致作为复现判据。

## 2. 关键算法 伪代码

### IP-69 SBB 蓝图编译与失败点校验
```
def compile_blueprint(components, touchpoints):
    FP, TR = [], {}
    for psi in components:
        for cert in psi.emitted_certs:            # 每个可能失败的证书
            # 找到承接该失败的最近前台触点（按交互链路）
            u = nearest_visible_touchpoint(psi, touchpoints)
            if u is None:
                raise BlueprintError(f"silent failure: {psi.name}.{cert}")  # 无触点=蓝图不完整
            fp = (u, psi, cert)
            FP.append(fp)
            TR[fp] = recovery_actions(psi, cert)  # 降级/排队/披露/升级，至少一个
    return Blueprint(touchpoints, components, FP, TR)

def blueprint_check(bp, live_state):
    for fp in bp.FP:
        u, psi, cert = fp
        if cert.invalid(live_state) and not bp.TR[fp]:
            return 'ERROR', fp                        # 无恢复动作 -> 禁止继续
    return 'OK', None
```

### IP-70 SLA-CERT 聚合、割集与恢复绑定
```
def sla_certify(component_certs, service_obs, bp, theta_svc, horizon):
    alpha_s = sum(c.alpha for c in component_certs)   # 并集界
    dims = {}
    dims['A']    = estimate_availability(service_obs, horizon)
    dims['L']    = estimate_latency(service_obs, horizon)
    dims['V']    = estimate_safety_violation(service_obs, horizon)
    dims['T_rec']= estimate_recovery_time(service_obs, horizon)
    dims['C_trans'] = disclosure_truthfulness(service_obs)  # 播报 vs 真实状态

    # 割集：找能同时击穿同一 SLO 的失败点组合
    cuts = min_failure_cuts(bp.FP, component_certs, dims, theta_svc)
    feasible = all(dims[d] <= theta_svc[d] for d in dims) and alpha_s <= 1 - 0.0
    # 任一安全相关 SLO（V）不被体验目标交换
    hard_ok = dims['V'] <= theta_svc['V']
    status = 'certified' if (feasible and hard_ok) else 'degraded'
    return SLACert(alpha_s=alpha_s, dims=dims, cuts=cuts, status=status, t=now)
```

### IP-71 BRR 复现判定与漂移再基线
```
def reproduce(beta, system, gamma=0.05):
    ms = [run_episode(system, seed=s, dist=beta.D, protocol=beta.protocol,
                      calib=beta.C) for s in beta.Sigma]
    m = aggregate(ms)
    # 双侧检验：指标是否落在容差 ε 内
    ok = abs(m - beta.m_ref) <= beta.eps and ttest(ms, beta.m_ref, gamma)
    return ReproCert(ok=ok, m=m, beta_id=beta.id, n=len(ms))

def drift_and_rebaseline(beta, live_stats, delta_max, cov_min):
    delta = two_sample_distance(live_stats.samples, beta.D.samples)  # MMD/卡方
    cov = support_coverage(live_stats.samples, beta.D)               # 支持集覆盖
    if delta > delta_max or cov < cov_min:
        return 'stale', {'delta': delta, 'cov': cov,
                         'action': 'mark_unreproduced_and_schedule_rebaseline'}
    return 'fresh', {'delta': delta, 'cov': cov}
```

### 服务契约层联合决策（置于 v23 全局决策之上）
```
def service_decision(c_t, omega_t, B_t, v_t, comp_certs, bp, beta, live_stats):
    # 1) 组件层先判安全硬约束（不因服务目标放宽）
    result, status = global_decision(c_t, omega_t, B_t, v_t, M, calib, S_phi, Q_safe)
    if status in ('fail-closed', 'energy'):
        # 2) fail-closed 必须走前台恢复，禁止静默停机
        rec = recovery_for(bp, comp_certs, reason=status)
        return result, 'fail-closed+recovery', rec
    # 3) 服务级契约评估与割集预警
    sla = sla_certify(comp_certs, live_stats, bp, theta_svc, horizon=H)
    if sla.status == 'degraded':
        return result, 'degraded+disclosure', sla
    # 4) 复现与漂移：未复现/漂移时只标注，不能反过来放行不安全动作
    rep = reproduce(beta, system)
    fresh, info = drift_and_rebaseline(beta, live_stats, delta_max, cov_min)
    if not rep.ok or fresh == 'stale':
        sla = sla.with_flag('unreproduced' if not rep.ok else 'drift')
    return result, 'served', sla
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| SBB 蓝图编译 | O(\|Ψ\|·\|cert\|·\|Φ\|) | O(\|FP\|) | 无无触点失败 ⇒ 蓝图完备；否则拒绝运行 |
| SLA-CERT 聚合 | O(\|cert\| + \|FP\|·k_cut) | O(2^{\|FP\|}) 割集（可剪枝） | 并集界 α_s≥真实失败概率；V 为硬约束 |
| BRR 复现 | O(n·T_ep) | O(\|Σ\|·d) | d(m,m_ref)≤ε 且通过检验 ⇒ 复现成立（显著水平 γ） |
| 漂移检测 | O(n·d + m·d) | O(n·d) | δ_t>δ_max 或 cov<cov_min ⇒ 强制标注待复现 |
| 服务决策 | O(组件决策 + \|FP\|·k_cut + n·T_ep) | O(\|Q\|+\|FP\|) | 安全硬约束前置；恢复必达前台 |

**正确性定理（v11-service）**：设组件证书失败概率为 α_i、服务预算 α_s，若 `Σ_i α_i ≤ α_s`，则 SLA 证书的并集界成立，`P(任一 SLO 破坏) ≤ α_s`。若 `V ≤ θ_V` 作为硬约束且在体验优化前判定，则 ECPS 的可用性项无法放松安全谓词。任意 `C_ψ` 失效时，SBB 的完备性保证存在 `u∈Φ` 与 `TR(fp)≠∅`，故 fail-closed 必然产生前台可感知的恢复动作，不存在静默失败。BRR 仅在 `d(m,m_ref)≤ε` 且通过统计检验时签发 Repro-Cert；`δ_t>δ_max` 或 `cov<cov_min` 时 SLO 声明被标注为「待复现」，不构成通过结论。

**割集保守性**：最小失败点割集给出 SLO 破坏的必要组合；只报告上界（可能过保守）而不低估，是安全侧可接受的。

## 4. 实验设计 E115–E120

| 实验 | 指标 | 门槛 |
|---|---|---|
| E115 蓝图失败点覆盖 | 失败点覆盖率、静默失败数 | 覆盖率 100%；静默失败 0 起 |
| E116 SLA 证书 soundness | 声明 α_s vs 实测破坏率 | 实测 ≤ 声明 α_s（不低估） |
| E117 基线复现保真 | 指标相对偏差、复现证书置信 | 偏差 ≤ 5%；覆盖 ≥ 95% 维度 |
| E118 漂移检出与再基线 | 检出延迟、误报率、再基线后偏差 | 延迟 ≤ 50 回合；误报 ≤ 5% |
| E119 服务恢复质量 | T_rec 分布、披露诚实度、排队长度 | P90 T_rec ≤ 3s；偏差 ≤ 5%；队列均值 ≤ 2 |
| E120 100h 服务闭环 | 可用性、安全违例、不可复现时长占比 | 可用性 ≥ 98%；安全违例 0；不可复现占比 ≤ 10% |

回退策略：E115 出现静默失败 → 阻止发布并补齐触点；E116 若并集界不成立（低估）→ 收紧 α_i 或改用 Bonferroni；E117 复现不达标 → 冻结声明并定位协议/标定差异；E118 误报过多 → 提高 δ_max 但保留 cov 硬门限；E119 恢复超时 → 增加降级模态与提前披露；E120 安全违例 → 立即回退到纯 fail-closed + 人工接管。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 体验压力绕过排队/披露 | 高 | 安全硬约束前置；V 维不可交换；Rec-Cert 强制签发 |
| 基线冻结在旧分布、假复现 | 高 | 支持集覆盖 cov 列为硬门限，不只比指标；δ 超阈强制标注 |
| 并集界过松导致 α_s 实际不达标 | 中 | 割集分析 + 组件 α_i 独立审计；必要时 Bonferroni 收紧 |
| 恢复动作本身不安全 | 高 | Rec-Cert 校验降级模态仍满足姿态/能量证书 |
| 披露信息不诚实 | 中 | C_trans 预算 + 红队比对播报与真实后台状态 |
| 蓝图随组件升级失同步 | 低 | 蓝图由组件证书声明自动生成，CI 强制重编译 |

## 6. 本轮最大风险

**一句话**：服务设计的「保可用性」与基线复现的「保通过」会形成双重激励——前者逼系统缩短排队与披露以维持前台响应，后者逼系统只在能复现旧指标的分布上宣称合格；两者叠加会让组件层安全证书被服务目标逐步架空、让漂移被漂亮的复现曲线掩盖，因此必须把安全硬约束置于 SLA 之上、把恢复动作纳入证书化并以支持集覆盖而非仅指标一致作为复现判据。
