# 第 8 轮 · STAC：长程不是步数，行为克隆要按评分加权，触觉要用“指令-观测差”代理

> 检索/复核日期：2026-10-26（UTC）。赛事身份不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「长程任务」「行为克隆」「触觉感知」。我先把它们各自钉到本轮核实到的官方事实上，再给主判断：**UniBot 的“长程”不是 100 步，而是 2–5 个可逆阶段链；行为克隆的真正错配不是模型太小，而是“帧均匀损失”对“成功率主排序”；触觉在这个赛道不是买传感器，而是把 Dex1 的夹爪编码器和关节跟踪误差变成接触代理。** 所以本轮不做更大的世界模型，也不做“触觉输入 VLA”，而是做 **STAC：Score-weighted、Stage-aware、Tactile-proxy 的行为克隆**——用评分步骤加权采样、可逆阶段图和 COD-Tac 接触代理，去同时修“接触富任务起步就挂”和“抓放任务倒在最后一下”这两个失败端。上一轮 PILOT 的“终局放置是闸门”只对了一半；这一轮把它拆成两种失败，并把预算从“补最弱轴/放置位姿”转到“阶段加权 + 接触代理”。

## 0. 本轮先核实：五个新事实，三个纠正

### 0.1 榜单已渲染出 8 个模型，但仍是“已公开、未验证”

本轮通过 `r.jina.ai` 渲染 `leaderboard.html`，第一次看到完整表格（此前直连被风控挡成 Coming Soon）：MolmoAct2/DexHacker 29.7%、39.0；WALL-OSS-0.5/Generalist Robotics 28.5%、38.9；DreamZero/World Model Lab 27.9%、37.9；Spirit-v1.5/VLAGO 25.9%、34.4；DM0/Embodied AI Institute 23.5%、31.7；PI-0.5/RoboReasoner 22.8%、30.6；GigaBrain-0/xembody 22.6%、29.5；GR00T N1.5/Humanoid Dynamics 20.5%、28.1（[S1][S2]，检索 2026-10-26）。用户说的“榜首不到 30%”得到确认：29.7%。

但必须保留三条反证：

- `runs.html` 虽是 256/256，详情页每个任务仍写“测试视频占位，后续可替换为真实视频文件”（[S3][S4]）。
- `leaderboard_data.json` 仍标 `generated_from: gen_leaderboard.py`（[S2]）。
- 规则说每个任务只跑 10 次（5 类泛化 × 2），若表格是原始 10 次，成功率应是 10% 的整数倍；但 JSON 里出现 27.29、27.85、37.32 这类值。

所以我把这份榜标记为 **“已渲染、未验证”**：可以读头部结构、模型身份和“不到 30%”这个上限，不能拿任务级小数做强归因。上一轮把它叫“占位”是保守的正确；这一轮它已经可见，但仍不是可引用的真机结论。**这也意味着：任何“某任务只有 21.3%，所以该任务最难”的论断都必须加“若数字为真”。**

### 0.2 规则纠正：成功率是主排序，步骤分只是 tie-break

官方参赛手册写得很清楚：实时榜单按 32 个任务的 **总平均成功率** 排序；成功率相同才看总平均步骤分；仍相同则早提交者靠前。每个任务 10 次独立运行，覆盖 5 类泛化（位置/干扰物/背景/未见物品/人为干扰），每类 2 次；单次最长 180 秒，超时算失败（[S5][S6]）。

这条比上一轮的“成功率与步骤分综合排序”更硬：**步骤分不是第二目标，只在并列时有用。** 因此上一轮“放置类步骤占 59.7%，所以要为步骤分优化放置”的算术要降级——它仍然是诊断工具（告诉你钱丢在哪一步），但不是优化目标。所有创新必须以“整任务成功”为唯一主指标；一个只提高过程分、不提高成功率的组件，排名价值接近零。

### 0.3 触觉纠正：API 没有触觉/力矩，Dex1 也没有触觉阵列

这是本轮最重要的“修剪”。挑战 API 的观测目录只有：4 路 RGB（左右高位 + 左右腕部）、双臂 7 维关节位置、双臂 EE 位姿（base 系）、左右夹爪开度、15 维下半身、单条语言指令；没有触觉阵列、没有关节力矩、没有电流、没有麦克风（[S11]，v2 README）。数据集同样只有 `observation.state.*` 和 `action.*` 的运动/夹爪流，没有 pressure/tactile 字段（[S10]）。

硬件侧：

- 挑战用的是 **Dex1-1 平行夹爪**：行程 90mm、夹持力 5–120N、电机状态反馈含 torque，但 API 不暴露；它没有触觉阵列（[S12]）。
- 有触觉阵列的是 **Dex3-1 三指手**（每手 33 个压力传感器，10g–2500g），但这不是本赛道的手（[S13]）。
- 连 Unitree 的 Dex3 公开数据集也只记录 28 维关节状态/动作，没有把触觉压力值放进 LeRobot 特征（[S14]）。

所以：**任何“接触觉输入”的 VLA 方案在这个赛道都是幻觉。** 可做的是三件事：

1. **夹爪编码器当 1 维触觉**：命令闭合 vs 实际开度，能判断“夹到/没夹到/夹多宽/是否滑移”。
2. **关节跟踪误差当力代理**：我们发出的关节目标与下一帧实测关节位置的差，在自由空间小、接触时大；这是 7 维/臂的“准力觉”。
3. **腕部视觉滑移 + 主动探测**：腕相机看夹爪/物体相对运动；插入时主动做小范围搜索，用跟踪误差当接触阈值。

这三件事合起来就是 **COD-Tac（Command-Observation Discrepancy Tactile proxy）**。它不是“真触觉”，但它是这个接口下唯一可落地、且能直接服务接触富任务的信号。

### 0.4 数据事实：33,276 条、169 小时、811GB，action/state 双流

HF collection 的 32 个数据集每任务 969–1,530 条，HangCup 实测 1,043 条/194,564 帧/30fps，`lastModified` 2026-10-14（[S9][S10]）。第三方统计给出 33,276 条、169 小时、约 811GB、G1 + Dex1 平行夹爪（[S15]）。数据结构是 LeRobot v3：四路相机（头双是 **rectified stereo**）、关节/夹爪/EE 位姿、`action.*` 命令流与 `observation.state.*` 测量流、5 条英文复述（[S10]）。

这给本轮两个可用条件：

- **头双是校正过的立体对**：不用额外深度相机，就能算视差/深度，把 2D 锚点升级成 3D 锚点。
- **action 与 state 同时存在**：离线可以算“命令-测量差”，训练 COD-Tac；线上我们保存自己发过的 action chunk，也能算同一量。

需要核验的一点：LeRobot 的 `action[t]` 是“t 时刻发给低层的目标”，`state[t]` 是“t 时刻测量”；两者是否严格同帧对齐、还是 action 领先一帧，要在数据上做互相关校准。这个对齐误差会直接影响 COD 的阈值，必须当成工程项而不是假设。

### 0.5 头部事实：前二都是 VLA，第三才是 WAM；底座选择是免费杠杆

公开技术报告能对上的头部方案：

- **MolmoAct2**（榜首）：Molmo2-ER 具身推理 VLM + flow-matching 连续动作专家 + 自适应深度 token；开放权重/数据/训练代码，Apache-2.0（[S16]）。
- **WALL-OSS-0.5**（次席）：4B VLA，20+ embodiment、每 epoch 超 100 万条轨迹，discrete action / multimodal / flow matching 三目标共训；Apache-2.0（[S17]）。
- **DreamZero**（第三）：14B 视频扩散 WAM，联合预测未来视频与动作，7Hz 闭环；强在零样本泛化，不在力觉（[S18]）。
- 后面还有 π0.5（co-training + 语义子任务，[S19]）、GR00T N1.5（Eagle VLM + DiT flow，[S20]）、GigaBrain-0（世界模型生成数据 + RGBD + CoT，[S21]）。

这组事实给出两个判断：

1. **架构不是当前瓶颈**：前二都是 VLA，第三是 WAM；WAM 的视频预测没有带来接触任务上的压倒优势，14B/7Hz 的成本却很高。**不要为了“世界模型”而上世界模型。**
2. **底座选择是免费杠杆**：MolmoAct2/WALL-OSS 都是 Apache-2.0 开放权重，且已经在同一张榜上证明自己能打。若规则允许（手册只限制“单一模型”，不限架构/来源），应该先做 1 周底座 bake-off，而不是默认从 Unitree WLA 或从头训。WLA-1.0-Base 仍是合规备选（Apache-2.0、6B、24GB 可微调）。

## 1. 榜单头部解剖：不是一种失败，是两种

### 1.1 头部模型的共同做法

把公开报告和榜单放一起，头部三名的共同点不是某个模块，而是：

- **大规模预训练 + 33k 任务数据微调**：MolmoAct2 用 3.3M 具身推理语料；WALL-OSS 用 20+ embodiment、百万级轨迹/epoch；DreamZero 用视频扩散先验。
- **视觉-语言-动作的端到端 BC**：没有显式的“第几步/阶段完成”状态；语言只有一条整任务指令；成功靠所有步骤完成。
- **没有力/触觉闭环**：输入是 RGB + 本体感觉；终端接触（插头、网线、锁、瓶盖、拉链）只能靠视觉和位置控制硬做。
- **通用模型，不是赛道专用**：它们强在语义/空间泛化，不强在 2–5 步桌面任务的分段可靠性。

### 1.2 一个结构性信号：头部 gap 更大

用榜单的“步骤分 − 成功率”当诊断量（不是优化目标）：

| 排名 | 模型 | 成功率 | 步骤分 | gap |
|---:|---|---:|---:|---:|
| 1 | MolmoAct2 | 29.7 | 39.0 | 9.3 |
| 2 | WALL-OSS-0.5 | 28.5 | 38.9 | 10.4 |
| 3 | DreamZero | 27.9 | 37.9 | 10.0 |
| 4 | Spirit-v1.5 | 25.9 | 34.4 | 8.5 |
| 5 | DM0 | 23.5 | 31.7 | 8.2 |
| 6 | PI-0.5 | 22.8 | 30.6 | 7.8 |
| 7 | GigaBrain-0 | 22.6 | 29.5 | 6.9 |
| 8 | GR00T N1.5 | 20.5 | 28.1 | 7.6 |

如果这些数字为真，头部三名的 gap 明显更大（9.3–10.4 vs 6.9–8.5）：**头部模型能把大部分过程分拿到，但整任务成功闸门过不去；尾部模型更早失败。** 这与“成功率主排序”结合，说明头部团队的边际收益在“最后一步的可靠性”，而尾部团队的边际收益在“基本抓取/放置能不能成”。两类团队的最优策略不同。

### 1.3 任务级：接触富任务输在起步，抓放任务输在终局

以榜首 MolmoAct2 的任务级数据为例（同样标“若为真”）：

- **最低成功率**：Disconnect Ethernet 21.3/28.0（gap 6.7）、Pick Out Battery 23.5/30.8（7.3）、Unlock 23.5/30.9（7.4）、Place Photo Frame 24.3/31.9（7.6）、Organize Pencil Case 24.9/32.8（7.8）。
- **最高成功率**：Color Arrangement 37.3/49.0（gap 11.7）、Organize Tools 37.2/48.9（11.6）、Pack Doll 37.0/48.6（11.6）、Paper Cup Stacking 35.3/46.3（11.0）。

这不是“所有任务都倒在最后一步”。它分成两种：

| 失败类型 | 任务例子 | 特征 | 主要修法 |
|---|---|---|---|
| **接触富任务的早期失败** | Disconnect Ethernet、Pick Out Battery、Unlock、Place Photo Frame、Organize Pencil Case | 成功率低、gap 也低：抓取/对位/接触还没建立就失败 | COD-Tac 接触察觉、CGI 接触引导插入、夹爪闭环抓取 |
| **抓放任务的终局失败** | Color Arrangement、Organize Tools、Pack Doll、Paper Cup Stacking、Clear Plates | 成功率高、gap 高：大部分步骤完成，最后放置/摆正/叠放失败 | SW-BC 终局加权、Stereo-PGL 3D 锚点、SVL 落点闭环 |

按粗分类，MolmoAct2 在 18 个接触富任务上平均 27.7/36.4（gap 8.7），在 9 个抓放任务上 32.9/43.2（gap 10.3），在 5 个纯放置任务上 31.2/41.0（gap 9.8）。**接触富任务整体更难，但抓放任务的“最后一公里”更明显。** 这就是本轮把“终局放置”拆成“接触起步 + 终局放置”两端的依据。

### 1.4 为什么不是“更大的世界模型”

DreamZero 是 14B、7Hz、视频扩散 WAM，排第三；MolmoAct2/WALL-OSS 是 VLA，排前二。WAM 的优势在“未见物理运动/环境”的泛化，但 UniBot 的失败更多是：

- 夹爪/接触状态不可见（视频里看不清是否夹住、是否插到位）；
- 2–5 步阶段的协变量漂移；
- 终端接触的力/位移关系，而不是未来画面长什么样。

视频世界模型能预测“画面会怎么变”，但不能直接给“夹爪是否滑、插头是否到位”的力觉；14B/7Hz 的推理成本还会挤压 180 秒内的重试预算。**本轮修剪：不做 full video WAM；最多做一个 10M 级的“接触世界模型”（CWM），只预测未来的 COD/夹爪/EE，不预测像素。**

## 2. 三个灵感词，各自钉到事实上

### 2.1 长程任务：不是 100 步，是 2–5 步的可逆阶段链

官方 32 个任务只有 2–5 个评分步骤（T16/T17 是 5 步，T31 是 3 步），公开榜单里 2 步任务平均 25.7%、5 步任务 23.3%，并没有“步数越多越差”的单调关系。**把“长程”理解成“需要更长上下文/更大规划器”是错的。**

UniBot 的“长程”体现在三个地方：

1. **阶段耦合**：上一阶段的结束状态就是下一阶段的开始状态；抓取偏 1cm，插入就插不进。
2. **可逆干扰**：官方 human 备注里大量“先叠后撤/拉上再拉开/合上再打开/拧开再拧回”，即阶段进度会 **倒退**；模型必须能检测并重做，而不是一条直线走到底。
3. **180 秒内的重试**：演示中位数约 6–10 秒，模型平均约 44 秒（若榜单时长为真），时间预算其实允许 1–2 次验证/重试；长程的敌人是“错了不知道”，不是“时间不够”。

所以长程的修法是 **SSG-2：可逆阶段图 + 入口/出口契约 + 进度头**，而不是 LLM planner。官方评分步骤已经把图给了；我们只需要把它变成状态机，并让模型知道“现在在第几步、上一步的出口条件是否满足”。PALM 的连续进度头（[S22]）和 Baton 的 transition-aware memory/入口条件（[S23]）都支持这个方向：长程失败主要不是“不会规划”，而是“阶段切换时入口状态不对/错误累积”。

### 2.2 行为克隆：帧均匀损失 vs 成功率主排序

所有头部模型本质上都是 BC（大规模预训练 + 任务数据模仿）。BC 的两个老问题在这个赛道被放大：

- **协变量漂移**：训练分布是干净演示，测试时从自己上一阶段的终点继续；小误差把状态推到演示没见过的区域，后面每一步都在 OOD 上。
- **帧均匀损失与评分权重错配**：一个 3 步任务里，终局步骤可能占 40 分，但终局接触帧只占整段视频的 20–30%；均匀采样会让模型把大部分容量花在“走近/张开手”这些低分帧上。

可直接做的修法：

1. **SW-BC（评分加权阶段采样）**：按官方步骤权重/阶段帧数采样，让每个阶段对损失的贡献接近它的评分权重；终局阶段再乘一个温和的 oversampling 系数（1.5× 左右），并设上限防过拟合。
2. **阶段提示**：推理时把“当前阶段文本 + 进度”作为内部 prompt 喂给同一个模型；不改变评测给的语言指令，也不引入第二个模型。
3. **chunk 级信用分配**：一个 action chunk 跨阶段边界时，用终局阶段的权重，不要用平均；对“没有推进进度”的 chunk 降权（GR-BC 的 chunk-level credit assignment 思路，[S24]）。
4. **恢复/undo 数据**：官方 human 备注就是现成的“阶段倒退”剧本；用它做恢复对，或至少让 FSM 能回退重做（AFIL 的 failure-informed 思路，[S25]；CCoL 对 BC 复合误差的分析，[S26]）。

这不是“换个更大的模型”，而是**把 33k 演示的用法改对**。在 169 小时数据已经够大的前提下，数据权重的边际收益高于再堆参数。

### 2.3 触觉感知：没有触觉传感器，只有触觉代理

触觉 VLA 在 2026 年确实很强：N0-VTLA 用大规模视触觉预训练 + 预测触觉通路（[S27]）；N0-TWAM 把触觉接触事件当任务分段信号（[S28]）；ForeTac-VLA 预测未来触觉，四个接触富任务平均 95%（[S29]）；Agile-WAM 用多时间尺度视觉/触觉预测，11.9ms（[S30]）；ILA 把接触动力学编码进 action latent（[S31]）；Uni-VLaT 用全身触觉把 VLA 的成功率拉高 43 点（[S32]）；τ 用未来视觉监督学触觉表示且不增加部署开销（[S33]）。这些工作证明了“接触信号值钱”，但没有一个能直接搬到 UniBot，因为 **UniBot 的 Dex1 没有触觉阵列，API 也不给力矩**。

所以本轮把触觉拆成“可用的代理”：

- **夹爪编码器**：Dex1 的开度范围 5.5–0.0（开→闭）。命令闭合后如果开度停在 2–4，说明夹到了；如果一路到 0，说明空夹；如果夹住后开度缓慢变大，说明滑移。这是最可靠的 1 维触觉。
- **关节跟踪误差**：`e_t = a_{t-1} - q_t`。自由空间小，接触/受阻时大；按关节归一化后，是一个 7 维/臂的力代理。
- **腕部视觉滑移**：腕相机上夹爪与物体的相对光流；夹住后物体相对夹爪移动 = 滑。
- **主动探测**：插入时做 1–3mm 的螺旋/微振，观察跟踪误差的上升/下降；误差上升=接触，下降=进入。这是“盲插”的经典做法，不需要力传感器。

这三者合成 **COD-Tac**，既作为策略输入，也作为辅助预测目标（预测未来 contact/slip），让模型在训练时学会“接触动力学”，推理时不需要触觉硬件。**这不是把触觉当输入，而是把触觉当监督 + 代理。**

## 3. 主判断：STAC

### 3.1 一句话

**把 33k 演示的行为克隆从“帧均匀”改成“评分步骤加权 + 阶段交接契约”，并用“指令-观测差”做无触觉硬件下的接触代理；主攻接触富任务的起步/插入和抓放任务的终局放置，而不是上更大的世界模型。**

### 3.2 组件

|---|---|---|
| **SSG-2 可逆阶段图** | 官方评分步骤→状态机；入口/出口契约；进度头；undo 回退 | 是（确定性代码 + 小头） |
| **SW-BC 评分加权 BC** | 阶段加权采样、终局 oversampling、chunk 信用分配、阶段 prompt | 是（训练+推理） |
| **COD-Tac 接触代理** | 夹爪编码器 + 关节跟踪误差 + 腕部滑移；接触/滑移/到位判定 | 是（输入+辅助头） |
| **CGI 接触引导插入** | 预插入位姿→螺旋搜索→COD 阈值→回退/重试 | 是（确定性控制） |

| **底座 bake-off** | MolmoAct2 / WALL-OSS / WLA 三选一 | 是（唯一学习模型） |

### 3.3 预期收益（可证伪）

- SW-BC：终局阶段帧仅占 20–30%，但评分权重 40–50%；温和重加权预期把终局步成功率抬 5–8pp，整任务 +2–4pp。
- COD-Tac + CGI：接触富 18 个任务若 +5–10pp，按 18/32 权重，整任务 +3–6pp。
- SSG-2 + 恢复：阶段切换/undo 失败若占 10–20%，修一半，整任务 +2–3pp。
- Stereo-PGL：抓放终局 +2–4pp，整任务 +1–2pp。
- 合计目标 **+5–8pp**（29.7% → 35–38%）；保守目标 +3–5pp。按 320 次、p≈0.3、SE≈2.56pp，+5pp 约 2 SE，是可检测的；+3pp 需要配对/多次评测。

**可证伪点**：若 T10/T26 插入调试槽的终局成功率提升 <5pp，则 COD-Tac/CGI 假设弱，回退到 SW-BC + Stereo-PGL；若 SW-BC 离线终局步 <3pp，则评分加权假设弱，回到均匀 BC + SVL。

### 3.4 为什么这比 PILOT 更该做

PILOT 的主线是“终局放置 + 少样本位姿迁移 + 检索”。它有两个未解问题：

1. **步骤分被当成第二目标**：规则是 success-first，步骤分只在 tie-break；PILOT 的“放置占 59.7%”算术不能直接转成排名收益。
2. **它假设“终局放置”是统一瓶颈**：但公开任务级数据（若为真）显示接触富任务失败更早，抓放任务才倒在终局；一个统一的“放置位姿迁移”修不了“夹爪没夹住/对位没对上”。

STAC 保留了 PILOT 的 SSG/PGL/SVL/OPT，但把主火力改成“BC 损失重加权 + 接触代理”，并且把“阶段”从评分步骤升级成可逆状态机。它更贴近规则（success-first）和硬件（无触觉/Dex1）。

### 1.2 规则：success-first，步骤分仅 tie-break

官方手册（[S5][S6]）关键条款：

- 仅设 **多任务通才模型** 赛道；必须单个模型完成全部 32 任务；不得混用多个模型。
- 不限制模型架构（World Model、VLA 等均可）。
- 每任务 **10 次独立运行**，覆盖 5 类泛化：位置、干扰物、桌面背景、未见物品、人为干扰；每类 2 次。
- 单次真机执行最长 **180 秒**，超时算失败；按执行情况计算步骤分。
- 实时榜单按 32 任务 **总平均成功率** 排序；成功率相同看总平均步骤分；仍相同则早提交者靠前。
- 有不计分的 **单任务测试通道**。
- 每队可获得 32 任务的全部真机数据；外部数据/预训练权重的许可**未明确**（默认合规 OFF，邮件确认）。

## 2. 榜单头部解剖：两种失败，不是一种

### 2.1 gap 与排名

用 `gap = step_score − success_rate` 做诊断（不是优化目标）：

- 头部三名：9.3、10.4、10.0。
- 后五名：8.5、8.2、7.8、6.9、7.6。

若数字为真，**头部模型拿到更多过程分但过不了成功闸门；尾部模型更早失败**。这与“success-first”结合：头部团队的边际收益在最后一步，尾部团队在基本操作。

### 2.2 任务级：接触富 vs 抓放

以 MolmoAct2 为例（[S2]，未验证）：

| 类型 | 任务数 | 平均成功率 | 平均步骤分 | 平均 gap |
|---|---:|---:|---:|---:|
| 接触富（插拔/拉链/拧盖/锁/电池/毛巾等） | 18 | 27.7 | 36.4 | 8.7 |
| 抓放/整理（pick-place） | 9 | 32.9 | 43.2 | 10.3 |
| 纯放置（叠杯/叠碗/放盘） | 5 | 31.2 | 41.0 | 9.8 |

- **最低成功率**：Disconnect Ethernet 21.3/28.0（gap 6.7）、Pick Out Battery 23.5/30.8（7.3）、Unlock 23.5/30.9（7.4）、Place Photo Frame 24.3/31.9（7.6）、Organize Pencil Case 24.9/32.8（7.8）。
- **最高成功率**：Color Arrangement 37.3/49.0（11.7）、Organize Tools 37.2/48.9（11.6）、Pack Doll 37.0/48.6（11.6）、Paper Cup Stacking 35.3/46.3（11.0）。

两种失败：

| 失败类型 | 任务例子 | 特征 | 主要修法 |
|---|---|---|---|
| **接触富早期失败** | Disconnect Ethernet、Pick Out Battery、Unlock、Place Photo Frame、Organize Pencil Case | 成功率低、gap 低：抓取/对位/接触没建立就失败 | COD-Tac、CGI、夹爪闭环抓取 |

**这不是说“接触富任务只需要触觉、抓放只需要放置”。** 接触富任务也可能倒在终局（Zip Up 的 gap 10.5、Remove Pinned Note 10.6），抓放任务也可能抓空。上表是“边际最可能”的归因，必须用调试槽验证。

### 2.3 为什么头部模型会这样

| 假设 | 机制 | 证据/置信度 |
|---|---|---|
| H1 帧均匀 BC 与评分权重错配 | 终局帧少但权重高；模型容量被低分帧占据 | 评分步骤公开（39.8% 终局）+ BC 文献（GR-BC/AFIL）；中高 |
| H2 阶段协变量漂移 | 上一阶段终点偏离演示分布，下一阶段在 OOD 上执行；错误累积 | PALM/Baton/CCoL；高 |
| H3 无接触/力反馈 | 插头/网线/锁/瓶盖/拉链的接触状态在 RGB 中不可见；位置控制硬做 | API 无触觉 + Dex1 无阵列；高 |
| H4 阶段不可逆干扰 | 官方 human 备注含 undo；模型没有“进度倒退”状态 | human_4 备注（叠后撤/拉上再拉开/合上再打开）；中高 |
| H5 任务级数据不均/长尾 | 每任务约 1k 条，但接触段短、成功恢复段少 | 数据统计；中 |
| H6 底座/适配不足 | 通用 VLA 未针对 G1 四相机/夹爪/桌面任务充分适配 | 头部排名与公开报告；中 |

### 2.4 为什么不是更大的世界模型

- DreamZero 14B/7Hz 排第三；前二 VLA。WAM 的强项是未见物理运动/环境泛化，不是接触力觉。
- UniBot 的失败更多是“夹爪是否夹住/插头是否到位/阶段是否交接”这类 **不可见接触状态**，不是“未来画面预测”。
- 14B/7Hz 的推理成本会挤压 180s 内的重试预算；视频扩散的随机性还会让延迟/动作统计不稳定（评测记录延迟与动作规律，[S11] §6）。
- **修剪**：不做 full video WAM；最多做 10M 级 CWM，预测未来 COD/夹爪/EE，不预测像素。

### 3.2 SSG-2：可逆阶段图

**输入**：`info.json` 的 `scoring_points_en`（或中文），解析出 `{text_i, weight_i}`；5 条复述/中文描述做任务匹配。

**图**：每任务 `G=(V,E)`，`V={s_0..s_k}` 线性阶段；`E` 含前向边和 **回归边**（当出口谓词 1→0 时回退）。

**每个阶段四件事**：

1. **阶段文本** `text_i`：用于内部 prompt。
2. **入口契约** `A_i(o_t)`：上一阶段出口必须满足的场景条件（例如“插头已夹住、插排竖直、插头尖在插座 5cm 内”）。
3. **出口契约** `B_i(o_t)`：谓词 + 稳定性（例如“插入到位、0.5s 内无位移、COD 保持接触”）。
4. **进度头** `p_i(t) ∈ [0,1]`：阶段内连续进度；`p>0.8` 且 `B_i=1` → 前进；`p>1.2` 且 `B_i=0` → 恢复；`B_i` 1→0 → 回退。

**状态更新伪代码**：

```python
def update_stage(o, c, s, p):
    # c: COD contact prob; o: observation; s: stage index; p: progress
    if exit_pred[s](o, c) and p > 0.8:
        return min(s + 1, K - 1), 0.0
    if s > 0 and exit_pred[s - 1](o, c) and not exit_pred[s](o, c):
        return s - 1, 0.5          # human undo / regression
    if p > 1.2 and not exit_pred[s](o, c):
        return s, 0.5              # retry current stage
    return s, p
```

**为什么不用 LLM planner**：官方步骤是固定的 2–5 步线性图；任务指令已给出；分支主要来自 human undo。一个小 FSM + 进度头足够，且延迟低、可审计。PALM 的进度头（[S22]）和 Baton 的入口/交接条件（[S23]）支持这个设计。

### 3.3 SW-BC：评分加权行为克隆

**问题**：标准 BC 对帧均匀采样：

```text
L_bc = E_{(o,a)~D} [ ||π(o) - a ||^2 ]     # 每帧等权
```

但评测是“全步骤成功 + 步骤分 tie-break”；终局阶段帧少、权重高。均匀采样让模型把大部分损失花在“走近/张手”这些低分帧。

**采样**：先按阶段采样，再在阶段内均匀采帧：

```text
P(s) ∝ w_s / Σ_j w_j          # 官方步骤权重
P(frame | s) = 1 / N_s
```

终局阶段乘温和系数 `γ=1.5`，并设上限 `ρ_max=3×` 均匀，防止过拟合：

```text
w'_s = min(ρ_max * (Σ_j w_j / K), γ * w_s)   # 例：K 个阶段，平均权重
```

**chunk 级信用分配**：

- 一个 action chunk 的权重 = chunk 第一帧所在阶段的权重；若跨阶段，取终局阶段权重（不要平均）。
- 对“没有推进进度”的 chunk 降权：`w_chunk *= (1 + α * Δp)`，`Δp = p_{t+H} - p_t`；`Δp≤0` 时乘 0.5。
- 这是 GR-BC 的 chunk-level credit 的轻量版（[S24]），不需要图搜索/奖励模型。

**阶段 prompt**：

```text
prompt = f"{task_instruction}. Current stage: {stage_text}. Progress: {p:.1f}."
```

评测给的语言不变；我们只是在策略内部追加阶段/进度文本。模型训练时用同样的模板（阶段标签来自弱分割），推理时由 SSG-2 生成。若底座不支持长 prompt，用学习到的 stage embedding 加到 action expert。

**损失**：

```text
L = L_flow + λ_stage L_stage + λ_prog L_prog + λ_contact L_contact
    + λ_anchor L_anchor + λ_ctx L_ctx + λ_reg L_reg
```

| 项 | 含义 | 起始权重 |
|---|---|---:|
| `L_stage` | 阶段分类交叉熵（弱标签） | 0.1 |
| `L_prog` | 阶段内进度 MSE（伪标签线性插值） | 0.1 |
| `L_contact` | 接触 BCE + 未来 COD MSE | 0.2 |
| `L_anchor` | 锚点/位姿与演示一致 | 0.1 |
| `L_ctx` | 检索上下文一致性（可选） | 0.05 |
| `L_reg` | undo/redo 恢复段加权 | 0.1 |

### 3.4 COD-Tac：指令-观测差触觉代理

**定义**：在时刻 `t`，执行完上一帧命令 `a_{t-1}`、收到观测 `o_t` 后：

```text
e_t^arm = (a_{t-1}^{arm} - q_t^{arm}) / σ_joint        # 7 维/臂，按关节尺度归一化
e_t^g   = g_{t-1}^{cmd} - g_t^{meas}                  # 1 维/夹爪；Dex1: 5.5 开 → 0 闭
v_t^slip = 腕部夹爪/物体相对光流                         # 2 维
c_t = σ(MLP([e_t^arm, e_t^g, Δq_t, v_t^slip, onehot(s_t)]))
```

**三种物理读数**：

1. **夹爪**：命令闭合后开度停在 2–4 → 夹到；一路到 0 → 空夹；夹住后开度缓慢变大 → 滑移。这是最强信号（1 维触觉）。
2. **关节跟踪误差**：自由空间小，接触/受阻大。按任务/关节计算自由空间基线 `median + k·MAD`；超过阈值 = 接触/受阻。**只做相对判定，不做绝对力标定。**
3. **腕部光流**：夹住后物体相对夹爪移动 = 滑；插入时物体/插座相对运动 = 未到位。

**训练标签**（弱监督，无需人工）：

- 阶段标签为“抓/插入/闭合/拉链/拧盖”的段 → contact=1；“接近/移动/释放”段 → contact=0。
- 夹爪命令 close 且开度 plateau >0.2s → grasp=1；开度到 0 → grasp=0。
- 关节残差高分段（>95 分位）→ contact=1；用变化点检测分段，避免逐帧噪声。
- 可选：少量人工标注（每任务 20–50 个事件）做校准。

**辅助预测**：让策略 latent 预测未来 `e_{t+1:t+H}` 与 `c_{t+1:t+H}`：

```text
L_contact = BCE(c_t, c_t*) + λ_f || e_{t+1:t+H} - ê_{t+1:t+H} ||^2
```

这模仿 ForeTac/N0-TWAM 的“预测未来接触”思路（[S28][S29]），但输入不是触觉，而是 COD；推理时不需要触觉硬件。

**控制门控**：

```text
if c_t > τ_contact and stage in CONTACT_STAGES:
    slow_down(0.5×); enable_servo(); enable_probe()
if c_t > τ_slip and stage in GRASP_STAGES:
    regrasp()
if c_t < τ_release and stage in INSERT_STAGES:
    push_forward(2mm); verify()
```

**校准**：每个任务在演示的自由空间段算 `e` 分布；接触阈值 = `median + 3·MAD`；夹爪阈值直接用开度 plateau。所有阈值写入任务配置，不跨任务硬套。

### 3.5 CGI：接触引导插入

针对 T10 PlugCharger、T26 PlugInEthernet、T05 DisconnectEthernet、T12 Unlock、T14 PourOutMedicine、T32 Syringe 等。

```python
def contact_guided_insert(obs, target_pose, axis, budget=3):
    move_to(pre_insert(target_pose, axis))          # 预插入，距目标 1-2cm
    align_with_wrist_and_stereo(obs)                # 腕部+立体深度对齐
    for attempt in range(budget):
        for r in spiral(radius_max=3mm, step=0.5mm):
            cmd = target_pose + r in plane + push(1mm along axis)
            send(cmd)
            c = cod(obs)                            # 关节跟踪误差/夹爪
            if c > tau_contact:
                # 接触：停止横移，轻推
                send(push(2mm along axis))
                if inserted(obs, c):
                    return True
                if c > tau_jam:
                    back_off(2mm); break
        rotate_small(2deg)                          # 换角度重试
    return False
```

- **成功判定**：插入深度 + COD 接触保持 + 视觉（插头/网线到位）+ 0.5s 稳定。
- **失败恢复**：回退 2mm、微转、重抓；最多 3 次；总时长守卫。
- **为什么有效**：Dex1 没有力传感器，但位置控制下的“跟踪误差”在接触时会上升；螺旋搜索把“看不见的孔”变成“可感知的接触地形”。
- **单模型合规**：CGI 是同一策略的确定性控制模式，不是第二个学习模型；在模型卡中披露。

### 3.6 Stereo-PGL：立体深度放置锚点

- 头双 `cam_left_high`/`cam_right_high` 是 rectified stereo；用 SGBM/RAFT-Stereo 在 240×320 上算视差，深度 `Z=fB/d`。
- 检测容器/目标（SAM 类或轻量检测器）→ 2D 框 → 立体深度 → 3D 点/面 → 3D 锚点（位置 + 朝向 + 容差圈）。
- 渲染锚点到头/腕图像；训练时用演示的真实目标做同一渲染，避免“渲染纹理域差”。
- 腕部保持高分辨率（360×480 或原生 480×640），头双降采样（240×320）；用 `image_resize` + `obs_delta_indices` 实现“接触区高分辨率、全局低分辨率”。
- 相机外参：离线标定；若 torso/waist 移动，用 `lower_body`/waist 做坐标变换；标定误差 >5mm 时退回 2D 锚点。

### 3.7 CWM：接触世界模型（可选）

- 10M 级 transformer/MLP：输入当前本体 + action chunk + stage，预测未来 H 步的 `e_arm`、`g`、`EE`（不预测像素）。
- 训练：33k 的 action/state 对，MSE；H=8–16（0.27–0.53s）。
- 推理：策略采样 1 个 chunk；CWM 预测；若预测接触/进度与当前 stage 不符，则 veto 并重采样（最多 2 次）。
- 成本：<5ms；不改变主模型。
- 门控：离线接触预测 AUC >0.8 才启用；否则关闭。
- 这是“混合 VLA + 轻世界模型”的版本，避免 DreamZero 式 14B 视频扩散。

### 3.8 推理循环

```python
class STACPolicy:
    def reset(self):
        self.s = 0; self.p = 0.0
        self.ah = deque(maxlen=4)          # action history
        self.retry = 0
        self.contact = 0.0

    def get_action(self, obs):
        # 1. COD
        e_arm, e_g, slip = cod_features(obs, self.ah)
        self.contact = contact_head(e_arm, e_g, slip, self.s)
        # 2. stage
        self.s, self.p = ssg.update(obs, self.contact, self.s, self.p)
        # 3. prompt + anchor
        prompt = stage_prompt(obs.language, self.s, self.p)
        anchor = stereo_pgl.render(obs, self.s) if PLACE_STAGE[self.s] else None
        # 4. policy
        chunk = self.base.act(obs, prompt, anchor, self.contact)
        # 5. contact gating
        if self.contact > TAU and self.s in CONTACT_STAGES:
            chunk = cgi.servo(chunk, obs, self.contact)
        # 6. record first action for next COD
        self.ah.append(chunk[0])
        return chunk
```

- `get_action` 每次返回固定 `T_a`；COD 用上一 chunk 的最后执行 action（`ah[-1]`）与当前观测。
- 阶段更新只在每次 `get_action` 调用时做；chunk 内部不更新。`T_a=4–8` 兼顾反应与吞吐。
- `reset()` 清空阶段/进度/动作历史/接触状态；每端口独立。

## 4. 数据引擎（TS-GPR 修剪版）

### 4.1 阶段弱分割

目标：给每条演示的每一帧一个阶段标签 `s∈{0..K-1}`，K = 官方步骤数，权重已知。

**特征**：夹爪开/合事件、EE 速度/加速度、腕部光流、COD 残差、停顿检测。

**算法**：

1. 检测夹爪事件（开→合、合→开）和 EE 停顿（速度 <ε 持续 >0.2s）作为候选边界。
2. 动态规划：把轨迹切成 K 段，最小化
   `Σ_seg [var(EE_speed) + var(COD) + λ·duration_penalty]`
   并约束段时长在演示分布的 5–95 分位内；边界优先落在夹爪事件/停顿处。
3. 用 20 条/任务人工抽检校准；F1 <0.7 的任务退回“只用官方文本 prompt，不做状态机门控”。
4. 输出 `stage[t]`、`progress[t]`（段内线性 0→1）、`contact_label[t]`（接触阶段/夹爪 plateau/残差高分）。

**注意**：分割是弱监督，不是 ground truth；训练时用置信度加权，低置信帧降权。

### 4.2 评分加权采样

- 阶段采样概率 `P(s) ∝ w_s`；终局 `γ=1.5`；上限 `ρ_max=3×` 均匀。
- 阶段内均匀；对“空夹/无效帧”做过滤（夹爪空夹、EE 静止 >1s）。
- chunk 权重：跨阶段取终局权重；`Δp≤0` 降权 0.5。
- 混合均匀 BC：保留 30–50% 的均匀采样，防止终局过拟合/遗忘接近段。

### 4.3 COD 特征

- 离线：对每条演示算 `e_arm[t] = a[t-1] - q[t]`、`e_g[t] = g_cmd[t-1] - g_meas[t]`；用互相关校准 action/state 对齐（滞后 0/1 帧）。
- 归一化：每关节用演示分布的 IQR；夹爪用 5.5 量程归一化。
- 标签：阶段接触标签 + 夹爪 plateau + 残差变化点；每任务阈值独立。
- 线上：保存上一 chunk 的最后 action；用当前观测算同一特征；动作历史 deque 长度 4。

### 4.4 恢复/undo 对

官方 human 备注是现成剧本（[S8]）：

| 任务 | 备注 | 场景化 | 恢复目标 |
|---|---|---|---|
| T27 | 叠了第二个之后拿下第二个 | 移除 bowl2 | 重放 bowl2 → 继续 bowl3 |
| T19 | 拉上拉链之后拉开 | 拉开拉链 | 重新拉合 |
| T14 | 拧开盖子之后拧动回来 | 盖回瓶盖 | 再拧开 → 倒药 |
| T17 | 笔盒合上之后手动打开 | 打开盒盖 | 重新合上 |
| T10 | 将插头拔起 | 拔出插头 | 重抓 → 插入 |
| T12 | 中途把锁拿走 | 锁被移走 | 重新定位 → 翻环 |
| T24 | 物品快到了然后放回传送带起点 | 目标远离 | 重抓 → 放置 |

**生成方式**：

- 有仿真：在阶段边界施加备注描述的刚体变换，重放恢复段。
- 无仿真：用“状态拼接”——从后续演示中找与 undo 后状态相近的帧，接到当前阶段前，训练恢复；只做辅助数据，权重 0.1。
- 至少让 FSM 能回退：`B_i` 1→0 时回退上一阶段，重跑该阶段策略；不依赖合成数据也能恢复。

### 4.5 数据预算

| 用途 | 来源 | 规模 | 备注 |
|---|---|---:|---|
| 主 BC | 官方 33k | 18.3M 帧 | 全量 |
| 阶段弱标签 | 官方 33k | 32×1k | 弱监督 |
| COD 特征 | 官方 33k | 18.3M 帧 | CPU 可算 |
| undo/redo | 官方备注 + 合成 | 32×2×50 ≈ 3.2k | 辅助，权重 0.1 |
| 立体标定 | 实测/数据 | 每机器人 1 组 | 棋盘格 |
| 外部实验室 | L2L | 600–1,200 条 | 可选，合规 OFF |

**结论**：主路径不需要新数据；33k 足够，关键是加权和接触信号。L2L 降为可选。

### 5.2 动作空间

- `control_space` 是首批超参：`ee`（6+6）vs `joint`（7+7）。
- 默认 `ee`：与 PGL/OPT 的 3D 锚点直接对齐，跨任务迁移好；低层控制器做 IK。
- 接触富任务可能更喜欢 `joint`（关节空间稳定、无需 IK 奇点）；在 bake-off 里用 T10/T26/T19 比较。
- 单模型只能选一个；训练时可双头，提交时按验证选择。
- `pivot`/`lower_body`：桌面任务多数固定底座；输出 hold/零，减少 DoF。若需要 waist 调整，只保留 1–3 维，不做腿。
- 夹爪：Dex1 范围 5.5（开）–0（闭）；抓取用“闭合到 plateau”而不是硬闭合；COD 直接读开度。

### 5.3 chunk 与延迟

- `action_chunk_size` 固定；候选 {4, 8, 16}。
- 30Hz 下 8 步 = 0.267s；若 p99 推理 100ms，占空比 73%；若 p99 200ms，选 16。
- 接触阶段希望短 chunk（反应快），自由空间希望长 chunk（平滑）；元数据只能一个值，选 8 为折中，接触阶段用 COD-gated servo 在 chunk 内降速/回退。
- 评测记录延迟稳定性（[S11] §6）：避免动态 early-exit/可变 batch 导致 jitter；固定计算图、预热、批处理；目标 p99 <100ms、抖动 <20ms。

### 5.4 底座与下半身

- 底座 bake-off 三选一（§6.1）；不要同时加载多个模型（单模型规则）。
- 下半身：桌面任务固定站姿；输出 hold。若数据集演示有 waist 动作，保留 waist 1–3 维，腿 hold。
- 这样减少 15+7 维动作，降低 BC 负担；代价是远距离物体可能够不到，用 waist 微调补偿。

### 5.5 立体深度

- 头双 rectified；SGBM 在 240×320 约 5–10ms；RAFT-Stereo 约 20–30ms（GPU）。
- 深度范围 0.2–1.5m；桌面平面拟合 + 容器检测；锚点投影。
- 透明/反光物体（试管、塑料杯）深度不稳 → 退回 2D 锚点 + 单目尺度先验。
- 相机外参离线标定；torso/waist 移动时用本体变换；误差 >5mm 禁用 stereo 锚点。

### 5.6 N 端口与隔离

- 评测方按 N 台机器人连接 N 个连续端口（8765 起），每端口独立 episode（[S11] §5）。
- 方案 A：每端口独立进程 + 独立模型副本（最稳，显存 N 倍）。
- 方案 B：共享推理后端 + 每端口轻量端点；必须请求隔离、每端口独立 `reset()`/状态、并发不阻塞。
- 健康检查、token 双处校验、soak 4h、延迟 p99、动作统计规律；FLEET 检查单保留为工程项，不作为研究轴。

### 5.7 单模型审计

- 唯一学习模型：底座 + 阶段/进度/接触头（同一 checkpoint 或同一服务的多个头）。
- 确定性代码：SSG-2、COD 特征、CGI、Stereo-PGL、FSM；在模型卡中逐项披露。
- 检索库/演示库是数据，不是模型；若使用 ICR，披露索引与缓存。
- 不按任务切换模型/LoRA；一个 checkpoint 服务 32 任务。
- 若规则对“脚本控制器”有异议，把 CGI 实现为策略的一个 mode（同一模型输出 + 确定性伺服），并提前邮件确认。

## 6. 训练配方

### 6.1 底座 bake-off（第一周）

| 底座 | 参数/许可 | 优势 | 风险 |
|---|---|---|---|
| MolmoAct2 | VLM+flow expert；Apache-2.0（[S16]） | 榜首；强空间/深度 grounding | G1 四相机/夹爪适配；推理成本 |

### 6.2 课程

见 §3.9。关键 gate：

- G1：阶段弱分割 F1 >0.8（否则只做 prompt，不做 FSM 门控）。
- G2：COD 接触 AUC >0.8（否则只做夹爪信号，不用关节残差）。
- G3：SW-BC 离线终局 +3pp（否则回退均匀 BC）。
- G4：调试槽 T10/T26 插入 +5pp（否则 CGI 降级为普通 SVL）。
- G5：整体无回归（抓放任务不掉 >2pp）。

### 6.3 超参

- LoRA r=64, α=128；action expert 全量/LoRA；AdamW；lr 1e-4/2e-5；cosine；warmup 3%；batch 64–128；bf16；chunk 8；horizon 1s；grad clip 1.0。
- 阶段采样 γ=1.5，ρ_max=3；均匀混合 40%。
- COD 阈值每任务校准；接触头 2 层 MLP（256）；CWM 4 层 transformer（d=256）。
- 早停：held-out 成功率 + 阶段诊断；训练 loss 只做参考。

### 6.4 算力

- 数据预处理/阶段分割/COD：CPU 8–16 核，1 周。
- bake-off：8×H100，1 周。
- 全课程：8×H100，2–3 周；CWM 1 周；Stereo 3–5 天。
- 推理：1×H100/A100；量化后 24GB 可跑 4B；p99 <100ms。
- 最小可运行版：只做 SW-BC + COD-Tac + SSG-2（不换底座、不做 CWM/Stereo），单卡 24GB 可微调 WLA/LoRA；这是 2 周可交付的版本。

## 7. 评测协议

### 7.1 离线（每天）

- 阶段弱分割 F1（10 条/任务人工抽检）。
- COD 接触 AUC / 夹爪抓取判定准确率。
- 终局步离线成功率：从演示的“终局前状态”启动策略，跑 50 次/任务，判谓词。
- 放置误差：Stereo-PGL 的 3D 锚点 vs 演示目标。
- 通过线：阶段 F1 >0.8；COD AUC >0.8；终局 +3pp；放置误差 <1cm。

### 7.2 本地（每周）

- 用 TCLB 做离线相对比较（不是主回路）：32×5×2 的回放/孪生混合，只做失败挖掘，不做模型选择。
- 接触富任务用小型 peg-in-hole/拉链简化仿真验证 CGI；不追求全物理。
- 记录延迟 p50/p99、动作抖动、阶段切换次数。

### 7.3 调试槽（版本门）

- 官方单任务不计分调试（[S5][S6]）：每个大版本 1 槽。
- 任务顺序：T10（插头）→ T26（网线）→ T19（拉链）→ T27（叠碗）→ T12（锁）→ T05（拔网线）。
- 判定：终局步成功率 ≥ +10pp 且无回归才进计分跑；若 <5pp，回退相应组件。
- 记录：每次调试槽的泛化类型、视频（若可用）、COD 阈值、失败阶段。

### 7.4 计分跑

- 计划 2 次：W7 中期、W8 终期；若只允许 1 次，W8 唯一。
- 提交前 4h soak：N 端口并发、状态隔离、健康检查、延迟 p99、token。
- 计分跑目标：整体 +5pp；保守 +3pp；接触富子集 +10pp；抓放子集不掉。

### 7.5 统计

- 总 320 次（32×10）；p≈0.3 时 SE≈2.56pp；+5pp 约 2 SE；+3pp 约 1.2 SE，需配对/多次。
- 每任务 10 次，任务级 SE≈14.5pp；**不要按单任务排名**；按接触富/抓放/纯放置三个子集聚合。
- 用 bootstrap 置信区间；若 CI 跨 0，不上线。

## 9. 创新点清单（持续迭代；动机/差异/可行性/资源/步骤/风险/状态）

> 状态：押注=本轮主线；保留=沿用；升级=旧点被改造；降级=保留但不再是主回路；砍=不做。

### I1 SSG-2 可逆阶段图（升级，押注）

- **动机**：success 要求全步骤；官方评分步骤已公开；human 备注含 undo；BC 需要阶段状态。
- **差异**：不是 LLM planner；把 `scoring_points` 变成可逆 FSM + 入口/出口契约 + 进度头；阶段 prompt 注入同一模型。
- **可行性**：解析 32 个 info.json；弱分割 + 小头；确定性代码；CPU 可跑。
- **资源**：33k 演示；1–2 人周；无需新数据。
- **步骤**：解析权重 → 弱分割 → 训练阶段/进度头 → FSM → 调试槽。
- **风险**：分割错误/阶段图不匹配/语言覆盖不足 → 置信度门控 + 退回纯 prompt。
- **状态**：押注。

### I2 SW-BC 评分加权行为克隆（新增，押注）

- **动机**：帧均匀损失与 success-first/评分权重错配；终局帧少但权重大。
- **差异**：按阶段权重采样 + 终局温和 oversampling + chunk 信用分配 + 阶段 prompt；不改架构。
- **可行性**：阶段标签来自 I1；只改 sampler/loss；33k 足够。
- **资源**：8×H100 1–2 周；无新数据。
- **步骤**：算阶段权重 → sampler → 训练 → 离线终局验证 → 调试槽。
- **风险**：终局过拟合/接近段遗忘 → 均匀混合 40% + 权重上限 + 早停看整体。
- **状态**：押注。

### I3 COD-Tac 指令-观测差触觉代理（新增，押注）

- **动机**：API 无触觉/力矩；Dex1 无触觉阵列；接触富任务最差；夹爪编码器 + 关节残差可用。
- **差异**：sensor-free 触觉代理；输入 + 未来接触辅助预测；不是触觉输入 VLA。
- **可行性**：action/state 双流；夹爪 1 维开度；关节位置；腕部光流；无需硬件。
- **资源**：33k；小 MLP；CPU/GPU 1 周。
- **步骤**：对齐校准 → 算特征 → 弱标签 → 训练接触头 → 集成门控 → 阈值校准。
- **风险**：残差混淆（惯性/摩擦/控制器滞后）；软物体弱；阈值漂移 → 只用相对判定 + 每任务校准 + 夹爪优先。
- **状态**：押注。

### I4 CGI 接触引导插入（新增，押注）

- **动机**：T10/T26/T05/T12/T14/T32 等插入/接触任务；无 force sensor；COD 可感知接触。
- **差异**：螺旋/微振搜索 + COD 阈值 + 回退/重试；不是端到端 BC 硬学。
- **可行性**：位置控制接口；180s 预算；确定性代码；调试槽可验证。
- **资源**：无新数据；1 人周；调试槽 1–2 次。
- **步骤**：预插入位姿 → 螺旋 → COD 阈值 → 到位判定 → 回退。
- **风险**：慢/卡住/单模型审计 → 预算 3 次 + 总时长守卫 + 模型卡披露。
- **状态**：押注。

### I5 Stereo-PGL 3D 放置锚点（升级，保留）

- **动机**：头双 rectified stereo 免费给深度；抓放终局失败；2D 锚点不够。
- **差异**：2D→3D 锚点；头低分辨率 + 腕高分辨率；训练/推理同渲染。
- **可行性**：SGBM/RAFT；离线标定；SAM 类检测；接口允许 resize。
- **资源**：1 GPU；标定 3–5 天；无新数据。
- **步骤**：标定 → 深度 → 检测 → 3D 锚点 → 渲染 → 训练 → 调试槽。
- **风险**：透明/反光/标定误差 → 退回 2D；误差 >5mm 禁用。
- **状态**：保留/升级。

### I6 CWM 接触世界模型（新增，可选）

- **动机**：full WAM 太重；小的接触动力学可做 chunk veto；DreamZero 证明世界模型有用但 14B/7Hz。
- **差异**：只预测未来 COD/夹爪/EE，不预测像素；10M 级；30Hz。
- **可行性**：33k action/state；小 transformer；<5ms。
- **资源**：1 GPU 周；无新数据。
- **步骤**：训练 → 离线 AUC → veto 集成 → 门控。
- **风险**：分布漂移/过度计算 → 只做 veto，AUC<0.8 关闭。
- **状态**：可选。

### I7 NRB undo/redo 恢复（升级，保留）

- **动机**：human 备注含 undo；阶段进度会倒退；BC 没见过恢复。

- **可行性**：32 任务备注已公开；刚体变换可合成；无仿真可用状态拼接。
- **资源**：3.2k 辅助对；权重 0.1；1 人周。
- **步骤**：解析备注 → 生成 undo 对 → 训练 → FSM 回退 → 调试槽。
- **风险**：备注不是测试剧本/合成失真 → 只做辅助 + 通用扰动兜底。
- **状态**：保留/升级。

### I8 ICR 检索条件化（保留，降为次要）

## 13. 开放问题

1. 公开榜单是最终真机结果还是演示/预生成数据？详情视频何时替换？任务级小数为何不是 10% 的倍数？
2. 单任务调试通道是否跑 10 次/5 类泛化，还是只跑 1 次？可用次数/成本？
3. 外部数据、公开预训练权重（MolmoAct2/WALL-OSS）是否允许？许可/披露要求？
4. 单模型定义：确定性 FSM/CGI/脚本控制器是否需在模型卡披露？是否算“混合多个模型”？
5. `action[t]` 与 `observation.state[t]` 的严格对齐（同帧/领先一帧）？COD 的阈值依赖它。
6. 评测控制频率、最大延迟、chunk 执行方式（是否严格 30Hz）？N 台机器人数量？
7. 步骤分的聚合公式（按 episode 平均？按步骤完成比例？）；成功率并列时如何使用？
8. human_1/human_4 编号含义与测试剧本；官方备注是否就是评测干扰？
9. `scoring_points` 的文本解析是否覆盖全部 32 任务；中英文权重是否一致？
10. Dex1 夹爪开度命令的物理含义（5.5 开–0 闭）与低层控制增益；COD 夹爪阈值需实测。
11. 透明/反光物体（试管、塑料杯）的 stereo 深度可用性；是否退回 2D。
12. 真实榜单发布后，重跑“两种失败”假设；用轴级数据替换公开占位。
