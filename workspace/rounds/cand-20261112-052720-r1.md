# 第 60 轮（承接第 59 轮「执行接地层」IP-145~151；灵感循环第 1 轮；本轮灵感：「角色一致性」×「任务分解」）

> 第 59 轮把证据链一路钉到电流环，堵住了「证据层自信、执行层失效」的抽象泄漏。但它仍默认一个更深的前提：**被承诺的「任务」是不可再分的原子单位，且执行主体始终是同一个无差别代理**。真实的具身系统里，任何非平凡任务都必须被**分解**成带依赖的子任务，分派给异质的**角色**——视觉探针、接触操作、力控末端、人类监督、不同技能库、不同机械臂甚至云端模型。任务一旦被拆开，「谁有权做哪一步」「哪一步的证据才算数」「预算如何在子任务间守恒」「子任务的实际表现是否仍属于它被声明的角色」就全成了未形式化的漏洞。本轮把两个灵感拧成一股：**角色一致性 = 任务分解的类型保持；任务分解 = 角色契约的构造性展开**。

## 0. 直觉与动机

### 直觉 1：任务分解不是「切蛋糕」，而是「签分包合同」

切蛋糕的隐喻是错的：它假设总任务可以任意切开、各块独立、拼回去仍是原任务。分包合同的隐喻才对：父任务把「效果责任」拆给子任务，但**权限不能被放大、证据义务不能被稀释、预算不能被超发、风险不能被隐藏**。一份合法分包合同必须同时满足两件事：

- **健全性（soundness）**：每个子任务做的事都不超出父任务允许的范围（不能越权、不能多花预算、不能把风险转嫁给父任务）。
- **完备性（completeness）**：父任务承诺的每个效果，都确有某个子任务负责覆盖（不能漏项、不能留下「没人负责的角落」）。

只做健全性，会得到一棵「干干净净但根本没干完活」的分解树；只完备性，会得到一棵「什么都敢干」的分解树。**角色一致性正是那个同时约束两端的类型系统。**

### 直觉 2：角色一致性有两副面孔

第一副是**结构角色（structural role）**：一个角色是一组静态契约——能力集、权限等级、每类证据的证据下限、预算配额、风险上限、实时契约包络、可访问的知识图谱范围、可产生的效果集。它是「编制」，写在任务分解之前。

第二副是**行为角色（behavioral role）**：同样的角色在真实执行中会「表现出」某种行为痕迹——用了哪些能力、触发了哪些权限、证据质量如何、消耗了多少资源。它是「实绩」，只能从执行证据里反推。

所谓角色一致性，就是**编制与实绩的双向对齐**：向下，分解必须让子角色是父角色的安全细化（结构一致）；向上，执行证据反推出的行为角色必须仍落在被声明角色的细化锥内（行为一致）。前者靠类型检查，后者靠贝叶斯归因。任何一侧破裂，都应当被当成**角色漂移**触发保守。

### 直觉 3：角色即类型，分解即带类型重写

把任务看成类型论里的「项」，把角色看成「类型」，那么分解就是一次**带类型的重写**：

- 原子任务（抓取、探测、推、抬）有原子角色类型；
- 顺序、并行、选择、条件分支各有其类型组合规则（role tensor）；
- 一次分解 `τ : R → {τ_i : R_i}` 合法，当且仅当子角色的张量 `R_1 ⊗ … ⊗ R_n` 是父角色 `R` 的安全细化，且父效果被覆盖。

这带来一个极强的性质——**类型保持（subject reduction）**：如果任务在类型 R 下良型，且它按规则重写为更细的任务，则新任务仍在（某个细化于 R 的）类型下良型。于是「角色一致性」不再是一句口号，而是「分解的每一步都不改变安全类型」这一可归纳证明的不变式。更进一步，**进展性（progress）**保证：良型的任务不会「卡住」，它最终要么带证书提交、要么安全停、要么降级/升级协商。

### 直觉 4：证书合成——叶子证明拼成父证明

第 59 轮的每个叶子接触都能产出一张 `Cert_eeis` 与一条 `EV-exec`。任务分解后，父任务的证书不应重新凭空论证，而应由子证书**合成**：分解证明树是一棵「证明项」，叶子是实测证书，内部节点是组合引理（顺序/并行/选择的健全性 + 角色张量不等式）。`compose` 只需检查每个内部节点的不等式是否成立，就能把「n 个局部安全」拼成「1 个全局安全」，并显式留下 `δ_decomp`（分解本身引入的额外风险）与 `E_used`（实际证据下限）。这把第 59 轮的「执行证据」从一次接触，抬升为**一棵可审计的证明树**。

### 直觉 5：预算与证据义务在分解树上守恒

第 59 轮的四重预算 `B_probe/B_ft/B_ux/B_exec` 是「一个代理的预算」。分解之后，预算变成树上的守恒量：并行子节点求和不得超过父节点，顺序子节点取最大复用，证据义务 `B_evidence` 也按同样方式守恒。任何「靠分解偷偷多要预算 / 偷偷降低证据义务」的方案，都会在类型检查时被拒。这让第 59 轮的 PCE+++ 升级为**角色感知的 PCE-R**：VOI 计算里再减去 `cost_role`（角色不可行惩罚 + 分解开销），不可行子任务在分解阶段就被剪枝。

## 1. 形式化定义（定义 153–160）

**定义 153（角色类型 Role Type）**
角色是一个八元组 `R = (C, A, E, B, Δ, T, K, Φ)`：
- `C ⊆ 𝒞`：允许使用的能力/技能/末端/探针集合；
- `A ∈ 𝒜`：权限等级（沿用能力格 A0<A1<A2…）；
- `E : ℰev → [0,1]`：每类证据（probe*/xmodal/human/ft/ux/exec）的**证据下限**，只有达到该强度才允许在本角色内提交；
- `B = (B_probe, B_ft, B_ux, B_exec, B_evidence)`：资源预算向量；
- `Δ ∈ (0,1]`：本角色任何承诺的风险上限；
- `T`：实时契约包络（继承第 59 轮 ERTC 的 WCET/抖动/内存/总线/续约周期）；
- `K ⊆ 𝒦`：可访问的 KG 子图范围与心智模型版本；
- `Φ ⊆ ℰℱ`：本角色允许产生的效果闭包（postcondition/effect set）。

**定义 154（安全细化 ⊑）**
称 `R₁` 是 `R₂` 的安全细化，记 `R₁ ⊑ R₂`，当且仅当：
```
C₁ ⊆ C₂,  A₁ ≤ A₂,  ∀e∈ℰev: E₁(e) ≥ E₂(e),  B₁ ≤ B₂（逐分量）,
Δ₁ ≤ Δ₂,  T₁ ⊑ T₂（更紧的实时包络）,  K₁ ⊆ K₂,  Φ₁ ⊆ Φ₂
```
直觉：**权限更小、证据更足、预算更少、风险更低、知识更窄、效果更少**。`⊑` 是一个偏序，其方向就是「安全方向」。任务分解只允许沿 `⊑` 向下走，绝不允许回头放大。

**定义 155（带类型任务项）**
任务项语法：
```
τ ::= atom(a) | seq(τ₁,τ₂) | par(τ₁,…,τₙ) | choice(τ₁,…,τₙ)
     | contingent(g, τ₁, τ₂) | call(skill) | abort(reason)
```
角色指派 `Γ : Node → Role`。良型判定 `Γ ⊢ τ : R`：原子任务要求 `R` 的能力集包含该原子所需能力且其效果在 `Φ` 内；复合任务由下述张量规则组合。`Γ ⊢ τ : R` 表示「τ 在角色 R 的契约内可分解执行」。

**定义 156（角色一致分解 RCTD 与角色张量 ⊗）**
对组合算子 `op ∈ {seq, par, choice, contingent}`，定义子角色张量 `R_⊗ = ⊗_{op}(R_1,…,R_n)`：
```
C_⊗ = ⋃ᵢ Cᵢ,   A_⊗ = maxᵢ Aᵢ,   E_⊗ = minᵢ Eᵢ,
B_⊗ = (Σᵢ Bᵢ^probe, Σᵢ Bᵢ^ft, Σᵢ Bᵢ^ux, Σᵢ Bᵢ^exec, Σᵢ Bᵢ^evidence)   # par / choice
     （seq / contingent 的预算按 max 复用，但证据义务仍按 min 取最严）
Δ_⊗ = Σᵢ Δᵢ（联合界）,  T_⊗ = ⨅ᵢ Tᵢ（包络交）,  K_⊗ = ⋃ᵢ Kᵢ,  Φ_⊗ = ⋃ᵢ Φᵢ
```
一次分解 `D : τ : R → {τ_i : R_i}` 是**角色一致**的，当且仅当同时满足：
- **(S) 健全性/无放大**：`R_⊗ ⊑ R`。子角色整体不越权、不增预算、不降证据、不抬风险、不扩效果。
- **(C) 完备性/效果覆盖**：`Φ ⊆ Φ_⊗`（父效果被覆盖），且父项中的每条依赖/守卫边都在子项依赖图中有对应（依赖覆盖），且不引入 `Φ_⊗ ⊄ Φ` 的「幽灵效果」（幽灵效果由 `(S)` 的 `Φ_⊗ ⊆ Φ` 已经排除，故实际要求 `Φ_⊗ = Φ`）。

记 `Γ ⊢ D : R`。**关键点：只有 (S) 是经典的「类型保持」，只有加上 (C) 才是安全的分解；(S) 防越权，(C) 防漏项，二者缺一不可。**

**定义 157（行为角色归因与角色漂移）**
对叶子执行证据 `e = EV-exec`，在角色格上做贝叶斯归因：
```
L(R | e) ∝ P(e | R) · π(R)
P(e | R) = 1[used_caps(e) ⊆ C_R] · 1[auth_ops(e) ≤ A_R]
           · ∏_q 1[evidence_quality_q(e) ≥ E_R(q)] · 1[resource(e) ≤ B_R]
```
得到后验 `P_infer(R)`。设声明角色为 `R_decl`，定义：
```
V_hard = 1[ ∃q: evidence_quality_q(e) < E_decl(q) ∨ used_caps(e) ⊄ C_decl ∨ auth_ops(e) > A_decl ]
D_soft = P_infer({ R' : R' ⋢ R_decl })        # 后验落在「不比声明更严」之处的质量
DR(e)  = V_hard + (1 − V_hard)·D_soft ∈ [0,1]
```
`DR ≤ θ_role` 为**行为角色一致**。注意方向：比声明**更严**的子角色仍算一致（它只是更保守），只有「更松或不可比」才计入漂移。这就是「角色一致性」的第二副面孔——**允许向下偏离，禁止向上偏离**。

**定义 158（证书合成与分解证明）**
分解证明树 `π_D` 的叶子是叶子证书 `(Cert_eeis, EV-exec, evidence_tag)`，内部节点是组合引理实例。合成算子：
```
compose(leaf)      = leaf.cert
compose(node)      = let {c_i} = map compose children
                     in  assert  R_used = ⊗_{op}(c_i.role)
                         assert  R_used ⊑ node.role
                         assert  Δ_used = Σ c_i.Δ + δ_decomp(node) ≤ node.role.Δ
                         assert  E_used = min_i c_i.E ≥ node.role.E
                         Certificate(role=node.role, Δ=Δ_used, E=E_used,
                                     cover=Φ_⊗ ⊇ Φ, children_hash=H({c_i}))
```
若所有内部节点断言成立，则称 `π_D` **合成健全**。`δ_decomp(node)` 显式记录「分解本身」引入的风险（组合近似误差、通信/同步开销、角色切换延迟）。

**定义 159（角色预算与 PCE-R）**
预算变成树上的守恒量 `B_role(node)`。对候选分解 `π`：
```
voi_role(π) = VOI_meta_pessimistic(π) − cost_exec(π) − cost_role(π)
cost_role(π) = λ_ev·max(0, need_evidence(π) − B_evidence(node))
             + λ_dec·δ_decomp(π) + λ_drift·1[∃leaf: DR_hat(leaf) > θ_role]
```
守恒约束：`par/choice` 节点 `Σ_children B ≤ B_node`；`seq/contingent` 节点 `max_children B ≤ B_node`；`B_evidence` 恒取 `min`（证据义务不可被并行摊薄）。不可行候选在分解阶段剪枝，而不是等到执行时才降级——这是把第 59 轮的「执行降级」前移到「分解期可行性判定」。

**定义 160（角色一致性证书 J_role 与 JCPS+++）**
```
J_role = (role_tree, Γ, decomp_proof π_D, leaf_cert_chain, drift_log,
          budget_snapshots, δ_decomp_log, version, hash_prev)
```
`verify(J_role)`：角色树逐层满足 `⊑`；每个内部节点合成健全；每个叶子 `DR ≤ θ_role` 且证书有效；预算守恒；版本单增且 `hash_prev` 链接。JCPS+++ 在第 59 轮输出上追加：`R_0, role_tree_hash, decomp_proof_hash, J_role, DR_max, B_role_snapshot`。

## 2. 关键洞察：健全性 × 完备性 = 双向角色一致

我一开始只想做「分解时检查子角色不超过父角色」——这是最自然的想法，但它只解决了一半。一个只满足 (S) 的分解树可以完全合法却**漏掉**父任务的关键效果（例如把「拧紧螺栓」分解成「对准」+「下压」却漏了「旋转」），此时所有子任务都安全完成，父任务却失败甚至造成更隐蔽的损害。反过来，只满足 (C) 的分解树会覆盖所有效果，却可能让某个子任务越权使用父任务未授权的能力。

因此真正的不变式是两句话：
> **向下不放大（soundness），向上不遗漏（completeness），横向不漂移（behavioral consistency）。**

这三者分别由 `R_⊗ ⊑ R`、`Φ_⊗ = Φ` 与 `DR ≤ θ_role` 承担。它们共同定义了「角色-任务双向一致」（Role-Task Bidirectional Consistency, RTBC）。

## 3. 与第 59 轮的关系：把「执行接地」抬到「组织接地」

第 59 轮的 BUQ/ERTC/EEIS/CLEP 解决的是「单个执行器是否可信」。本轮的 RCTD/RDA/CCP 解决的是「由多个异质角色组成的执行组织是否可信」：

- `BUQ` 的 `ξ_exec` → 变成**每个叶子角色的执行不确定性**，在各子任务上独立辨识；
- `ERTC` 的实时契约 → 变成**角色 T 的实时包络**，并在分解时按 `seq/par` 组合（顺序复用、并行求和）；
- `EEIS` 的阻抗证书 → 变成**叶子证书**，由 `CCP` 合成为父证书；
- `CLEP` 的单次闭环 → 变成**叶子上的闭环**，`PCE-R` 负责在分解树上调度；
- `XMC+` 的执行模态 → 在 `RDA` 中升级为**角色归因模态**：执行证据不仅对账「环境信念」，还对账「角色声明」。

一句话：第 59 轮给系统装上了「本体感觉」，第 60 轮给它装上了「组织纪律」。

## 4. 复杂度与正确性直觉

- 角色细化检查：`O(|C|+|E|+|K|)`，可哈希缓存，分解期一次。
- 效果覆盖检查：对效果集做集合包含，`O(|Φ|)`；依赖覆盖对子图做支配性检查，`O(|V|+|E_dep|)`。
- 行为归因：角色格大小 `|ℛ|` 通常 ≤ 数十，`O(|ℛ|·d_e)`/叶子。
- 证书合成：`O(树节点数 + Σ证书大小)`，本质是一次后序遍历。
- PCE-R 额外开销主要在分解可行性剪枝，`O(|CP|·|分解候选|·|ℛ|)`，相对第 59 轮的 UKF/μ 分析可忽略。

正确性直觉（详见产物区 RCDS 定理）：若根角色 `R₀`、分解 `π_D` 角色一致（(S)+(C)）、所有叶子证书有效且无漂移、合成健全，则由 `⊑` 的传递性与联合界，父承诺满足 `R₀` 的风险上限与证据下限，且 `P_safe ≥ 1 − Σ_leaf δ_leaf − δ_decomp − Σ_leaf drift_penalty`。反过来，任何一处 `⊑` 逆流、效果遗漏或漂移越界，都能被对应的局部检查捕获，不会静默通过。

## 5. 本轮最大风险（一句话）

**最大风险是：类型检查只能保证「分解相对于声明是自洽的」，却无法保证「声明本身是对的」——一旦父角色或父效果集在建模时就漏掉了真实世界的某个效果/权限/依赖（`Φ` 自身不完备），再严密的 `⊑` 与效果覆盖也只会在一个错误的封闭世界里自证清白；因此必须把「父角色/父效果的完备性」当作独立的外部假设（A），并用真实世界的反例探针与人类监督持续证伪它，绝不能让内部类型一致性冒充外部世界正确性。**

```python
from dataclasses import dataclass, field
from typing import FrozenSet, Dict

@dataclass(frozen=True)
class BudgetVector:
    probe: int
    ft: int
    ux: int
    exec_: float
    evidence: float

    def __le__(self, o):   # 逐分量 ≤
        return (self.probe <= o.probe and self.ft <= o.ft
                and self.ux <= o.ux and self.exec_ <= o.exec_
                and self.evidence <= o.evidence)

@dataclass(frozen=True)
class RoleType:
    caps: FrozenSet[str]          # 能力/技能/末端/探针
    auth: int                     # 权限等级
    evidence_floor: Dict[str, float]  # 证据类 -> 下限
    budget: BudgetVector
    risk_ceiling: float           # Δ
    rt_contract: "RealTimeContract"   # 复用第 59 轮 ERTC
    kg_scope: FrozenSet[str]      # KG 子图 + 心智模型版本
    effects: FrozenSet[str]       # 效果闭包 Φ

def refines(r1: RoleType, r2: RoleType) -> bool:
    """r1 ⊑ r2 ：r1 是 r2 的安全细化（向下不放大）"""
    if not r1.caps <= r2.caps: return False
    if not r1.auth <= r2.auth: return False
    if not all(r1.evidence_floor.get(e, 0.0) >= r2.evidence_floor.get(e, 0.0)
               for e in r2.evidence_floor): return False
    if not (r1.budget <= r2.budget): return False
    if not (r1.risk_ceiling <= r2.risk_ceiling): return False
    if not contract_refines(r1.rt_contract, r2.rt_contract): return False
    if not r1.kg_scope <= r2.kg_scope: return False
    if not r1.effects <= r2.effects: return False
    return True

def contract_refines(t1, t2) -> bool:
    """实时包络更紧：WCET/抖动/内存/总线更小，周期更短"""
    return (all(t1.WCET_map[k] <= t2.WCET_map[k] for k in t2.WCET_map)
            and t1.Jitter_bound <= t2.Jitter_bound
            and t1.Mem_pool <= t2.Mem_pool
            and t1.Bus_bw_reserved <= t2.Bus_bw_reserved
            and t1.Renewal_period <= t2.Renewal_period)

def tensor(roles, op) -> RoleType:
    """角色张量 ⊗：组合子角色的整体契约"""
    caps   = frozenset().union(*[r.caps for r in roles])
    auth   = max(r.auth for r in roles)
    ev     = {e: min(r.evidence_floor.get(e, 1.0) for r in roles)
              for e in set().union(*[set(r.evidence_floor) for r in roles])}
    if op in ("seq", "contingent"):
        budget = BudgetVector(max(r.budget.probe for r in roles),
                              max(r.budget.ft for r in roles),
                              max(r.budget.ux for r in roles),
                              max(r.budget.exec_ for r in roles),
                              min(r.budget.evidence for r in roles))
    else:  # par / choice
        budget = BudgetVector(sum(r.budget.probe for r in roles),
                              sum(r.budget.ft for r in roles),
                              sum(r.budget.ux for r in roles),
                              sum(r.budget.exec_ for r in roles),
                              min(r.budget.evidence for r in roles))
    risk   = sum(r.risk_ceiling for r in roles)     # 联合界
    t      = met_contract([r.rt_contract for r in roles])   # 包络交
    kg     = frozenset().union(*[r.kg_scope for r in roles])
    eff    = frozenset().union(*[r.effects for r in roles])
    return RoleType(caps, auth, ev, budget, risk, t, kg, eff)
```

### IP-153 RCD（角色一致分解）

```python
@dataclass
class DecompositionNode:
    task: "TaskTerm"
    role: RoleType
    mode: str                     # seq/par/choice/contingent/atom
    children: list                # List[DecompositionNode]
    proof: "DecompProof" = None

class RoleViolation(Exception):
    pass

def decompose(task, role, mode=None) -> DecompositionNode:
    """把带类型任务项分解为子节点，并强制 (S) 健全 + (C) 完备"""
    if is_atomic(task):
        if not atom_capabilities(task) <= role.caps:
            raise RoleViolation(f"atom {task} needs caps outside role")
        if not atom_effects(task) <= role.effects:
            raise RoleViolation(f"atom {task} produces effect outside role")
        return DecompositionNode(task, role, "atom", [])

    mode = mode or task.mode
    subs = plan_subtasks(task, role)               # 规划器给出候选子任务
    child_roles = [assign_role(s, role) for s in subs]
    for cr in child_roles:
        if not refines(cr, role):
            raise RoleViolation("child role is not a refinement of parent")

    R_tensor = tensor(child_roles, mode)

    # (S) 健全性 / 无放大
    sound = refines(R_tensor, role)
    # (C) 完备性 / 效果覆盖 + 依赖覆盖 + 无幽灵效果
    effect_cover = (task.effects == R_tensor.effects) and (R_tensor.effects == role.effects)
    dep_cover = dependencies_covered(task, subs)
    complete = effect_cover and dep_cover

    if not (sound and complete):
        raise RoleViolation(f"sound={sound} complete={complete}")

    children = [decompose(s, cr) for s, cr in zip(subs, child_roles)]
    proof = DecompProof(mode=mode, parent=role, children=child_roles,
                        R_tensor=R_tensor, delta_decomp=estimate_delta_decomp(subs))
    return DecompositionNode(task, role, mode, children, proof)

def dependencies_covered(parent, subs) -> bool:
    """父依赖图的每条边都能在子任务依赖图中找到对应支配路径"""
    parent_edges = dependency_edges(parent)
    sub_reach = transitive_closure(dependency_edges_of(subs))
    return all(e in sub_reach for e in parent_edges)
```

### IP-154 RDA（角色漂移归因）

```python
def role_drift(e: "ExecEvidence", declared: RoleType, lattice: list,
               theta_role: float = 0.1):
    """行为角色一致：允许更严、禁止更松。返回 (DR, posterior, consistent)"""
    # 硬越权：直接判不一致
    hard = (not used_caps(e) <= declared.caps
            or auth_ops(e) > declared.auth
            or any(evidence_quality(e, q) < declared.evidence_floor.get(q, 0.0)
                   for q in declared.evidence_floor))
    if hard:
        return 1.0, {declared: 1.0}, False

    # 软归因：在角色格上做贝叶斯后验
    loglik = {}
    for R in lattice:
        lp = 0.0
        lp += 0.0 if used_caps(e) <= R.caps else -np.inf
        lp += 0.0 if auth_ops(e) <= R.auth else -np.inf
        for q in R.evidence_floor:
            if evidence_quality(e, q) < R.evidence_floor[q]:
                lp += -np.inf
        for k, used in resource_usage(e).items():
            if used > getattr(R.budget, k):
                lp += -np.inf
        loglik[R] = lp + np.log(prior(R))
    posterior = softmax(loglik)
    # 只统计「不细于声明」的后验质量：比声明更严是安全的
    loose_mass = sum(p for R, p in posterior.items()
                     if not refines(R, declared))
    dr = loose_mass
    return dr, posterior, dr <= theta_role
```

### IP-155 CCP（证书合成）

```python
@dataclass
class ComposedCertificate:
    role: RoleType
    delta: float              # 已用风险（联合界）
    evidence: dict            # 实际证据下限
    cover_ok: bool            # 效果覆盖
    children_hash: str
    version: int

def compose_certificates(node: DecompositionNode) -> ComposedCertificate:
    if not node.children:                       # 叶子
        leaf = node.leaf_cert
        dr, _, ok = role_drift(leaf.ev_exec, node.role, ROLE_LATTICE)
        if not ok:
            raise RoleViolation(f"role drift at leaf: {dr:.3f}")
        return ComposedCertificate(node.role, leaf.delta, leaf.evidence,
                                   cover_ok=True,
                                   children_hash=hash(leaf), version=leaf.version)

    child_certs = [compose_certificates(c) for c in node.children]
    R_used = tensor([c.role for c in child_certs], node.mode)

    # 合成健全性断言
    if not refines(R_used, node.role):
        raise RoleViolation("compose: child tensor not refinement of parent")
    delta_used = sum(c.delta for c in child_certs) + node.proof.delta_decomp
    if delta_used > node.role.risk_ceiling:
        raise RoleViolation(f"compose: delta {delta_used} > ceiling {node.role.risk_ceiling}")
    ev_used = {q: min(c.evidence.get(q, 1.0) for c in child_certs)
               for q in node.role.evidence_floor}
    if any(ev_used[q] < node.role.evidence_floor[q] for q in ev_used):
        raise RoleViolation("compose: evidence floor violated")
    cover = (node.task.effects == R_used.effects)

    return ComposedCertificate(
        role=node.role, delta=delta_used, evidence=ev_used, cover_ok=cover,
        children_hash=H([c.children_hash for c in child_certs]),
        version=max(c.version for c in child_certs) + 1)
```

### IP-156 PCE-R（角色感知探-诺-演）

```python
def probe_commit_evolve_role_aware(x0, M, task, budget, consent, operators):
    route = plan_on_map(M, task, risk_model)
    sched, log = [], []

    for cp in route.checkpoints:
        if not budget.exec_snapshot.is_viable_for_contact():
            return negotiate_or_stop(cp, M, "exec_budget_exhausted")

        # ① 分解期：先做角色一致分解，再做任何执行
        try:
            D = decompose(cp.task, Gamma(cp), mode=cp.mode)
        except RoleViolation as exc:
            log.append(EvidenceRecord(ev="EV-role", rejected=True, cp=cp, reason=str(exc)))
            alt = redecompose_or_reroute(M, cp, exc)
            if alt: route = alt; continue
            return negotiate_or_stop(cp, M, "role_infeasible")

        # ② 预算树守恒检查 + 可行性剪枝
        if not budget_tree_conserves(D, budget):
            return negotiate_or_stop(cp, M, "role_budget_violation")

        # ③ 逐叶子执行（每叶子走第 59 轮 CLEP）
        if not budget.role_snapshot.viable(D):
            return negotiate_or_stop(cp, M, "role_budget_exhausted")

        for leaf in D.leaves_in_dependency_order():
            delta_f_req = risk_model.delta_f(leaf.role)
            M, fused, D_plus, EV_exec, cert = closed_loop_exec_probe(
                M, leaf.checkpoint, delta_f_req, budget)

            dr, posterior, ok = role_drift(EV_exec, leaf.role, ROLE_LATTICE)
            M.drift_log.append((leaf.id, dr, posterior, ok))
            if not ok or EV_exec.degraded_flag:
                alt = redecompose_conservative(M, cp, leaf, dr)
                if alt: D = alt; break
                return negotiate_or_stop(cp, M, "role_drift")

        # ④ 证书合成：叶子 → 父
        try:
            parent_cert = compose_certificates(D)
        except RoleViolation as exc:
            return negotiate_or_stop(cp, M, f"compose_failed:{exc}")

        # ⑤ 角色预算扣除（守恒）
        budget_tree_spend(budget, D)

        # ⑥ 承诺（带角色证书）
        gate = evidence_gate_ppp_role(tag_evidence_role(D, M), M, parent_cert)
        if select_gait(schedule_risk(D, M)) != "halt" and gate[0] == "ok":
            sched.append(commit(D, select_gait(schedule_risk(D, M)), parent_cert))
            log.append(gate)
            continue

        alt = reroute(M, cp, risk_model)
        if alt and select_gait(schedule_risk(alt, M)) != "halt":
            route = alt
            continue
        return negotiate_or_stop_ppp(cp, M, D, schedule_risk(D, M), consent,
                                      tau_int=operators.active.consent_timeout(),
                                      mu_mis=operators.active.mu_mis)

    return sched, log, M

def budget_tree_conserves(D, budget) -> bool:
    for node in D.postorder():
        if node.mode in ("seq", "contingent"):
            need = {k: max(getattr(c.role.budget, k) for c in node.children)
                    for k in BUDGET_KEYS}
        else:
            need = {k: sum(getattr(c.role.budget, k) for c in node.children)
                    for k in BUDGET_KEYS}
        if any(need[k] > getattr(node.role.budget, k) for k in BUDGET_KEYS):
            return False
        if min(c.role.budget.evidence for c in node.children) < node.role.budget.evidence:
            return False
    return True

def evidence_gate_ppp_role(tagged, M, parent_cert):
    """在第 59 轮七类证据门基础上，追加角色证书与覆盖检查"""
    if not (parent_cert.cover_ok and len(M.drift_log) > 0):
        return ("reject", "role_coverage_or_drift", tagged)
    return evidence_gate_ppp(tagged.base, M, tagged.persona,
                             M.ood_reg, tagged.ev_exec)
```

### IP-157 J_role（角色一致性证书）

```python
@dataclass
class RoleCertificate:
    role_tree: DecompositionNode
    gamma: dict
    decomp_proof: DecompProof
    leaf_cert_chain: list
    drift_log: list
    budget_snapshots: list
    delta_decomp_log: list
    version: int
    hash_prev: str

    def verify(self) -> tuple[bool, str]:
        # 1. 角色树逐层细化
        if not all(refines(c.role, n.role)
                   for n in self.role_tree.postorder() for c in n.children):
            return False, "role_tree_not_refining"
        # 2. 每个内部节点合成健全
        try:
            compose_certificates(self.role_tree)
        except RoleViolation as exc:
            return False, f"compose:{exc}"
        # 3. 叶子漂移守界
        if any(dr > THETA_ROLE for _, dr, _, _ in self.drift_log):
            return False, "role_drift_exceeded"
        # 4. 预算守恒
        for snap in self.budget_snapshots:
            if not snap.conserves():
                return False, "budget_not_conserved"
        # 5. 版本与哈希链
        if self.version <= 0 or not self.hash_prev.startswith("0x"):
            return False, "bad_version_chain"
        return True, "ok"
```

### IP-158 CEB-r（角色作用域云边隔离）

```python
def cloud_edge_role_update(cloud_pkg, edge_state, n_shadow=20):
    """云端按角色作用域下发技能/固件/参数，隔离区影子验证后热切换"""
    # 1. 下发包必须声明其目标角色作用域 R_scope 与细化证明
    if not refines(cloud_pkg.role_scope, edge_state.active_role):
        return "reject", "scope_amplification"

    # 2. 影子运行 n_shadow 次，采集漂移分布与角色张量一致性
    drift_samples, compose_ok = [], True
    for _ in range(n_shadow):
        ev = shadow_run(cloud_pkg, edge_state)
        dr, _, ok = role_drift(ev, cloud_pkg.role_scope, ROLE_LATTICE)
        drift_samples.append(dr)
        compose_ok &= ok

    # 3. 验收：漂移 99% 分位数守界 + 合成健全 + 预算守恒
    if not compose_ok:
        return "reject", "shadow_role_violation"
    if np.percentile(drift_samples, 99) > THETA_ROLE:
        return "reject", "shadow_drift_distribution"
    if not budget_tree_conserves(cloud_pkg.example_tree, edge_state.budget):
        return "reject", "shadow_budget_violation"

    hot_swap(cloud_pkg)
    return "accept", "ok"
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| RTA | `O(|C|+|E|+|K|+|Φ|)`/细化检查，可哈希缓存 | `O(|ℛ|·d_R)` | `⊑` 偏序；细化可传递、可合成 |
| RCD | 分解 `O(|τ|·|ℛ|)`；效果覆盖 `O(|Φ|)`；依赖覆盖 `O(|V|+|E_dep|)` | `O(|τ|·d_R)` | (S) `R_⊗⊑R` + (C) `Φ_⊗=Φ` 双检查 |
| RDA | `O(|ℛ|·d_e)`/叶子 | `O(|ℛ|)` | 硬越权零容忍；软漂移方向性（更严安全） |
| CCP | `O(树节点数 + Σ证书大小)`；后序遍历 | `O(树节点数)` | 合成健全：`⊑` 传递 + 联合界 + 证据 min |
| PCE-R | 相对第 59 轮增加 `O(|CP|·|分解候选|·|ℛ|)` | 复用 CLEP + 预算树 | 预算树守恒；漂移/不可行即再分解或停 |
| J_role | `O(1)`/接触追加，`O(树)` 验证 | `O(接触数+|树|)` | 版本哈希链、逐层细化、合成可复算 |

**正确性定理（Role-Task Bidirectional Consistency Soundness, RTBC-S）**
假设 A22–A55（第 53–59 轮）成立；并新增：
**(A56)** 角色类型建模：真实执行主体的能力/权限/证据/预算/风险/实时/知识/效果均落在所声明角色类型的域内；`⊑` 的实现与语义一致（无漏判）。
**(A57)** 分解完备性：规划器给出的 `Φ` 在建模宇宙内完备——真实任务所需效果 T 与允许效果 Φ 满足 `T ⊆ Φ`（即父角色声明不漏掉真实世界效果）；`plan_subtasks` 不丢依赖边。
**(A58)** 角色归因：`P(e|R)` 诚实刻画证据在角色 R 下的产生分布；`DR` 的硬指标可判定、软后验校准良好（ECE_role ≤ ε_role）。
**(A59)** 证书合成：`δ_decomp` 诚实上界分解本身引入的风险；`compose` 的联合界与证据 `min` 规则音完备；叶子证书不可篡改、版本化。
**(A60)** 角色预算：`B_role` 在树上守恒（并行求和、顺序取最大、证据取 min）；`cost_role` 诚实上界真实角色开销。
**(A61)** 根角色 `R₀` 的风险上限 `Δ₀` 与任务级 `δ_f` 满足 `Δ₀ ≤ δ_f`。

则：
1. **无放大性（No-Amplification）**：沿分解树向下，`C`/`A`/`B`/`Δ`/`K`/`Φ` 单调不增，`E` 单调不减；任何子任务都不可能越权、超预算、降证据、抬风险、扩效果、越知识域。
2. **无遗漏性（No-Omission）**：若 `Φ_⊗=Φ` 且依赖覆盖成立，则父任务的每个效果与每条依赖都由某子任务承担；不存在「所有子任务成功但父任务漏项」的分解。
3. **行为角色一致性**：若所有叶子 `DR ≤ θ_role`，则以 `≥1−θ_role` 的概率，实际执行未越出声明角色的细化锥；更严的执行被允许，更松的执行被拒绝。
4. **合成健全性**：若 `π_D` 合成健全，则父证书满足 `Δ_used=Σ_leaf δ_leaf+δ_decomp ≤ Δ₀`、`E_used=min_leaf E_leaf ≥ E₀`、`Φ_⊗=Φ`，且父承诺的风险不高于叶子风险联合界。
5. **组织级部署界**：
```
P_safe ≥ 1 − Σ_cp [ Σ_{leaf∈D(cp)} δ_leaf + δ_decomp(cp)
                    + δ_role_model + δ_drift(cp) + δ_compose(cp) ]
         − P(Φ 建模不完备) − P(依赖图漏边) − P(根角色声明错误)
         − P(护盾回退失败) − P(J_role 版本链断裂)
```
关键：前四项（`δ_leaf`、`δ_decomp`、`δ_role_model`、`δ_drift`、`δ_compose`）都是**内部可检查**的；后三项（`Φ` 不完备、依赖漏边、根角色错误）是**外部假设**，只能靠真实世界反例与人类监督证伪——这正是本轮最大风险所在。
6. **终止性**：PCE-R 在有限分解深度与预算内终止于 {承诺(带 J_role), 再分解, 绕行, 降档, L2 协商, 安全停, 角色不可行停}；`compose` 是树上的有根后序遍历，必然终止。

## 6. 本轮最大风险
