# 第 1 轮（UniBot 线 · MVP 轮；本轮灵感：「UniBot」×「最小可行产品」）

> **轮次说明与基线**：本轮不推翻 UniBot 线的事实底盘，而是换一个"算子"重做第 1 轮。上一版把三个灵感编译成 8 个创新点（IP-01…IP-08）的**研究纲领**；本轮用「最小可行产品」对它做**减法与重排序**，只保留能在一次真机评测里被证伪的最小闭环。旧编号 U1–U12 / L1–L7 / E601–E618 封存（仍可作背景引用）；本轮启用 **M1–M9 / P1–P7 / E619–E634**。
> **事实纪律**：本轮未新增联网检索（检索工具不可用），赛事 / 接口 / 数据事实沿用上一轮 2026-11-17 的核实结果；凡涉及"评测每任务跑多少 episode、per-task 结果是否回传、chunk 执行端语义"等未知项，一律显式标为**未知**，并转化为 MVP 的探针任务，而不是当成假设。

## 0. 与 MVP 决策直接相关的六条事实（其余从略）

1. **UniBot = `unibot.unitree.com` 的 UniBot 世界挑战赛**；UniBot-V1 通才模型赛道，Unitree G1 真机，32 项桌面操作任务（抓取 / 放置 / 双手协调），5 类泛化场景，按**平均成功率 + 平均步骤分**排名。
2. **数据**：官方 32 个 LeRobot v3.0 数据集（≈32k episodes / 169 h），G1 + Dex1 夹爪，4 路 480×640@30fps（头 stereo×2 + 左右腕）。
3. **提交**：本地部署 observation→action 服务，暴露 `metadata` / `get_action` / `reset`；`control_space ∈ {joint, ee}` 互斥；chunk 长度自定；`obs_delta_indices` 同时决定观测传输与叠帧；`image_resize` 在**评测端**执行；token 须在 `metadata` 与每步 `meta.token` 两处校验；N 台真机随机顺序、连续端口 `8765…8765+N−1`、每端口独立全流程；官方采集 per-step 延迟波动与动作统计规律性用于可信度评估。
4. **榜单 JSON 是 teaser / 占位表**（`gen_leaderboard.py` 随机生成、被"即将公开"遮罩）→ 只能当**结构说明书**，不能当优化目标；真实终稿与真实评测预算未知。
5. **跨基准同形**（RoboDojo）：策略能推进大半程，崩在最后的对齐 / 插入 / 放置 / 恢复。
6. **关键未知（MVP 必须优先买断）**：官方每任务跑多少 episode？是否回传 per-task 结果？chunk 在执行端是否插值 / 平滑？`reset()` 的调用边界？N 的实际取值与端口绑定方式？——这些不是"实现细节"，它们直接决定 A/B 的功效与可行性。

## 1. 直觉：MVP 不是"小一号的模型"，而是"最便宜的一次有效证伪"

第一性原理有三条：

**(a) 比赛里最稀缺的资源不是算力，而是"可信的真机结论"。** 真机时段不可随时获得，teaser 榜不是终稿，代理指标与真机的关系未知。因此一个研究方案的真实成本不是代码行数，而是

`J = 工程时间 + 真机 episode 数 × 单 episode 机会成本 + 被取消资格的风险期望`。

MVP 应最小化这个**期望证据成本**：用最少的不可逆资源，换到最强的可归因结论。

**(b) 成功率是 ~25% 的二值量，统计功效是硬约束。** 在 p≈0.25 时，要用 80% 功效、α=0.05（双侧）检出 **+5 个百分点**的绝对提升，约需 **1250 episodes/臂**；检出 **+10 点**约 **326/臂**；检出 **+15 点**约 **150/臂**（推导见产物区 P1）。这意味着一件事：

> 凡是预期效应 < 最小可检测效应（MDE）的改动，无论多优雅，都**不该进入 MVP**——不是因为它错，而是因为**你无法知道它对不对**。

**(c) 上一轮"通用 = 技能向量"的红利（teaser oracle +4.26）恰好落在 MDE 以下。** 它不是假的，而是**不可测的**：真实兑现率若为 40%–60%，全局效应只有 +1.7…+2.5 点，远低于合理真机预算下的 MDE。故技能路由（IP-01）被本轮从 MVP 中移除，降为"预算充裕后再做的规模化项"。

**合成**：UniBot 的赛制把"可部署性"抬到与"模型能力"同等权重；而「最小可行产品」要求先交付**能被评测、能被归因、能被回滚**的东西。于是 MVP 不是"一个更强的小模型"，而是：

> **一个永远能跑通的最小提交（S0）+ 一个单点机制（S1）+ 一套接口体检（C）+ 一条预注册判决（D）。**

其中 S1 的唯一候选是 **GraspGuard（抓握守卫）**：不是上一轮的全套 GraspVerify（可抓性判定 + 非抓取原语 + 改抓），而是缩到最小——**只检测"空抓 / 滑移"，只做有界重抓**。理由：它在最难 6 个任务上预期效应最大、依赖最少、不需要任何新数据采集。

## 2. 严谨定义（M1–M9）

**定义 M1（MVP 五元组）** `MVP = (S0, S1, C, D, B)`：`S0` 是不可变的安全基线提交；`S1` 是在 `S0` 上只加**一个**机制的提交；`C` 是接口合规性检验集；`D` 是预注册判决规则；`B` 是回滚包（保证 S1 失败时能退回 S0）。

**定义 M2（合规谓词与有效得分）** `Conf(S) ∈ {0,1}`：S 在评测端满足"端口 / 握手 / token / 字段 / 形状 / chunk / reset 隔离 / 延迟预算"全部硬约束。定义 **`Score(S) = Conf(S) · E[success | S]`**。注意乘法结构：`Conf=0` 时一切模型能力归零。

**定义 M3（最小可检测效应）** 对两臂独立二项比较，`n(δ) = (z_{1-α/2}+z_{1-β})² · [p1(1−p1)+p2(1−p2)] / δ²`；`MDE(n)` 为其反解。

**定义 M4（主终点与分层）** 先验选定难任务子集 `T*` 与控制子集 `T_ctrl`；主终点 `Δ* = E[succ | S1, T*] − E[succ | S0, T*]`；次终点为 32 任务全局均值；安全终点为 `T_ctrl` 上的伤害上界。

**定义 M5（效应集中度）** 若真实效应只在占比 `f=|T*|/32` 的任务上为 `δ`、其余为 0，则全局效应为 `fδ`；达到相同功效所需全局 episode 数是分层设计的 `1/f²` 倍。

**定义 M6（可证伪的提交）** 一次提交"可证伪"当且仅当提交前写定 `(H0, H1, T*, n, α, 判决规则)`，且 `n` 由 M3 反解；提交后不得改主终点。

**定义 M7（单因子提交）** 相邻两次提交之间只允许一个机制差异（`S1 − S0`）。若需同时评估多个机制，先用离线 / 代理评测做**预筛选**，真机只做**确认**。

**定义 M8（有界干预）** 干预必须满足：触发需 `P(empty) > τ_hi` 且相位 ∈ {lift, transport} 且 `n_retry ≤ N_max`；每次干预有固定时间预算；超预算或重试耗尽则**无条件回退到基线行为**。

**定义 M9（探针提交）** 第一次提交 `S0` 的首要目的不是分数，而是**测协议**：每任务 episode 数、per-task 是否回传、chunk 执行语义、reset 边界、N 与端口、延迟分布。其产出是 `protocol.json`，用于校准后续所有 `n` 与判决。

## 3. 定量分析：MVP 的可行性由功效而非模型决定

**3.1 功效表**（两臂独立、等样本、α=0.05 双侧、power=0.8、p1=0.25）

| 目标效应 δ（绝对百分点） | 每臂 episode 数 | N=4 台并行、45 s/ep 的双臂真机时长 |
|---|---|---|
| +3 | ≈3394 | ≈21.2 h |
| +5 | ≈1248 | ≈7.8 h |
| +10 | ≈326 | ≈2.0 h |
| +12 | ≈230 | ≈1.4 h |
| +15 | ≈150 | ≈0.94 h |
| +20 | ≈86 | ≈0.54 h |

读法：**+5 点不可作为 MVP 的主终点**（约 1250/臂，而 teaser 本身还是占位数据）；要么把主终点定在**效应集中的难任务层**，要么只追求 ≥+10 点的机制。

**3.2 分层为什么是决定性的（M5）**

若 6 个难任务（teaser 均值 ≈21.4%）上 GraspGuard 把成功率从 21.4% 抬到 35.4%（+14 点），则：

- 分层主终点（n≈160/任务/臂）需 `6×160×2 = 1920` episodes，N=4 时 ≈6.0 h；
- 若错误地只看 32 任务全局均值，效应被稀释为 `(6/32)×14 ≈ +2.6` 点，需 `1/(0.1875)² ≈ 28×` 的样本量，**同一笔预算下必然判为不显著**。

⇒ MVP 的第一条工程纪律：**先声明估计对象，再花真机时间**。

**3.3 结论（可执行的三条）**

- **V1（只做可测的）**：主终点放在预注册的难任务层；全局均值只作次要。
- **V2（只做一个机制）**：S1 只加 GraspGuard；chunk 缝合、技能路由、上下文适配、姿态先验全部移出 MVP。
- **V3（先买协议）**：第一次提交用于探针（M9）；没有 `protocol.json` 之前，不训练、不调参、不承诺 `n`。

## 4. MVP 的取舍：8 个 IP 的"留 / 缓 / 砍"

| 原 IP | MVP 处置 | 理由 |
|---|---|---|
| IP-06 代理评测 + 六因子 | **留骨架，降为离线 H** | 六因子是预注册与归因的语言；但不作为真机判决依据 |
| IP-02 抓握确认 + 改抓 | **留最小核：GraspGuard（空抓 / 滑移 + 有界重抓）** | 断点直击、无新数据、效应可集中于难任务层 |
| IP-03 chunk 缝合 | **拆开：延迟 / 审计留，缝合缓** | 缝合依赖未知执行语义；MVP 不碰未验证语义 |
| IP-01 技能 MoE | **砍出 MVP** | 预期全局效应 < MDE；且合规未确认 |
| IP-04 上下文适配 | **砍出 MVP** | 效应弥散、合规未确认 |
| IP-05 姿态先验 | **砍出 MVP（只留零成本探针）** | pivot 语义未知，收益可能为 0 |
| IP-07 双空间 | **砍出 MVP** | 不是本轮瓶颈 |
| IP-08 审计 | **留最小核（token / 端口 / 延迟 / reject 计数）** | 属于 M2 合规谓词，不是可选优化 |

一句话：**MVP 只保留"决定能否被计分"的工程 + "决定能否被证伪"的测量 + "唯一一个够大的机制"。**

## 5. 研究问题（MVP 轮）

- **Q1（协议未知）**：能否用一次探针提交买断评测协议（episode 预算、per-task 回传、chunk 语义、reset 边界）？买不到时如何退化为离线 + 保守假设？
- **Q2（效应集中度）**：GraspGuard 的收益是集中在"插入 / 旋转 / 细粒度"难任务层，还是弥散？这决定主终点，也决定项目生死（见 §7）。
- **Q3（误判不对称）**：在只有 1 维夹爪标量与腕部视觉的条件下，能否把"空抓 / 滑移"的**高精度**检测做到 `P(empty)>0.9` 才介入，使净收益为正？
- **Q4（合规 / 可审计）**：单 checkpoint + 单服务 + 有界干预，是否天然满足"单模型通才"与"动作规律性"审核？探针能否同时自证延迟与动作分布？

## 6. 设计原则（MVP 版）

- **N1 先合规，后能力**：`Score = Conf · success`，合规是乘性前置。
- **N2 先估计，后优化**：没有主终点与 `n`，不许开始训练。
- **N3 单因子提交**：一次只改一个机制；其余靠离线预筛。
- **N4 有界干预**：所有在线介入必须有触发阈值、次数上限、时间预算、回退路径。
- **N5 安全基线不可变**：S0 冻结版本；S1 永远可一键回滚。
- **N6 不碰未验证语义**：chunk 插值、pivot 跟踪、reset 边界未实测前，不做任何依赖它们的优化。

## 7. 本轮最大风险

**一句话**：MVP 的最大风险是把"可验证性"误当成"竞争力"——如果 GraspGuard 的真实收益是弥散的小效应而不是集中于难任务层的大效应，分层主终点会把它判成噪声并砍掉，最后交付一个"跑得极稳、测得极准、但分数不足以竞争"的安全产品。

## 8. 下一轮计划（三条）

- 先跑 **E619（探针）** 与 **E620（体检）**；没有 `protocol.json` 与 `conformance_report.json` 就冻结一切训练。
- 再跑 **E623–E627**（抓握伪标签、校准、离线 AUROC、离线 A/B）；离线 AUROC < 0.85 或净收益离线为负即砍。
- 最后跑 **E630**（真机分层 A/B）；`Δ*` 的 95% CI 下界 > 0 且控制层无灾难性伤害才发布 S1。

## 0. 结论摘要

**MVP = 五件套**：

| 件 | 内容 | 一句话验收 |
|---|---|---|
| **S0** | 冻结的基线 VLA 提交（单 checkpoint、joint 空间、固定 chunk=8） | 连续 3 次提交 0 reject、0 超时、分数可复现 |
| **S1** | `S0 + GraspGuard`（只检测空抓 / 滑移，只做有界重抓） | 难任务层 `Δ*` 的 95% CI 下界 > 0，控制层无灾难性伤害 |
| **C** | 接口体检 C1–C18 | `conformance_report.json` 全绿 |
| **D** | 预注册判决（主终点 / n / α / 停手规则） | 提交前锁定，提交后不改 |
| **B** | 回滚包（镜像 + 配置 + 运行手册） | 5 分钟内退回 S0 |

**关键数字（本轮的"解析结果"，非真机实测）**：

- 主终点：预注册 6 个难任务层，`p1≈21.4%`；
- 目标效应：`δ=+14` 点 → `n≈160 / 任务 / 臂`，共 `6×160×2 = 1920` episodes；
- 控制层：2 个任务 × 100/臂 = 400 episodes（仅灾难监测，P7 说明它检不出 3–5 点小伤害）；
- 预算：N=4 台并行、45 s/ep ≈ **7.3 h**；N=8 ≈ **3.7 h**；
- 若只看 32 任务全局均值，同一效应被稀释为 +2.6 点，需约 28× 样本 ⇒ **分层是生死线**；
- 预计全局增益仅 +2.6 点，因此 **S1 不是"靠总分赢"的方案，而是"靠难任务层可归因胜出 + 全局不伤"的方案**；冲总分的规模化项（IP-01 技能路由）留到预算充裕阶段。

**一页流程**：`探针 S0（E619）→ 体检 C（E620）→ 离线抓握标签与校准（E623–E626）→ 分层真机 A/B（E630）→ 判决 → 发布或回滚`。

## 2. 提交服务规格（S0 / S1 共用骨架）

### 2.1 架构

```
评测端 (N robots, ports 8765..8765+N-1)
        │  websockets + msgpack + numpy
        ▼
┌──────────────────────────────────────┐
│ N 个轻量前端（每端口一个）             │
│  - 持有本端口 session（绝不共享）      │
│  - 校验 token、字段、形状、chunk 长度  │
└──────────────┬───────────────────────┘
               │ 进程内 / 本机 IPC
               ▼
┌──────────────────────────────────────┐
│ 共享后端（单 checkpoint）              │
│  - 主干策略（冻结）                    │
│  - GraspGuard（S1 才启用）             │
│  - 延迟兜底 + 审计埋点                 │
└──────────────────────────────────────┘
```

**硬约束**：`session` 以端口为键；任何"上一次动作 / 重试计数 / 相位缓存"都必须落在端口内。**跨端口读取 = 直接判失败风险**，由 C12 浸泡测试覆盖。

### 2.2 metadata 模板（字段以官方 example 为准，提交前逐项核对）

## 4. GraspGuard 规格（S1 的唯一机制）

### 4.1 直觉与可观测信号

腕部相机随末端运动。因此：

- **抓住了** ⇒ 物体在**腕部坐标系**里近似静止（相对位移小），且夹爪闭合后标量保持在闭合值；
- **空抓** ⇒ 夹爪闭合但物体仍在腕部画面里"随世界移动"；
- **滑移** ⇒ 物体在腕部画面里缓慢漂移，同时 EE 在动。

三路信号：**腕部相对运动**（主）、**夹爪标量**（次）、**EE 位姿差分 / 速度**（门控）。

### 4.2 伪标签（用官方数据自动生成，不采新数据）

对每个 episode，找到"夹爪由开→闭"的时刻 `t_c`，之后取窗口 `[t_c, t_c+W]`：

```
u = 物体在腕部帧内的相对位移（特征点 / 光流 / 分割质心）
g = 夹爪标量轨迹（Dex1：开 ≈5.5 → 闭 ≈0）
v = EE 在世界系（或基座系）的位移
```

- `y = 1`（抓稳）：`g` 保持闭合 **且** `u < ε_u` **且** `v > ε_v`（真的抬/移过，排除"没动过"）；
- `y = 0`（空抓/滑移）：`v > ε_v` **且** `u > ε_u`；
- 其余为**歧义样本**：不训练，只统计占比。

**必须承认的偏差**：(i) 透明 / 反光 / 可变形物体上 `u` 估计不可靠；(ii) "腕部静止"也可能来自"物体被桌面卡住"；(iii) 未见物品上伪标签分布漂移。→ 这些不是脚注，而是 §9 的 R3/R4。

### 4.3 模型与校准

- 输入：左右腕两帧（可加相邻帧差分）+ 夹爪标量 + EE 速度；
- 主干：ResNet18 / ViT-S 级小网（≤6 ms/步目标）；
- 输出：`P(empty)`；
- 校准：温度缩放（temperature scaling），在**按任务留出**的验证集上拟合；报告可靠性图与 ECE；
- 阈值：`τ_hi` 取使**假阳率（把抓稳误判为空抓）≤2%** 的最小值——因为误判成本不对称，MVP 只允许"高精度、低召回"。

### 4.4 介入状态机（有界）

```
IDLE ──(g_closed 且 t - t_close > 0.3s 且相位∈{lift,transport})──► TEST
TEST ──(P(empty) > τ_hi 且 n_retry < 2)──► REGRASP
TEST ──(否则)──────────────────────────► IDLE
REGRASP: 开 → 沿接近轴后退 Δ → 前进 Δ → 合 → 等 0.3 s
REGRASP ──(第 2 次仍 P(empty)>τ_hi)──► FREEZE（放行基线，不再干预）
任意状态 ──(超时 / 异常)──► IDLE（基线继续）
```

**有界性**：最多 2 次重抓；每次 ≤3 s；单 episode 干预总时长 ≤6 s；任何不确定都回退。

### 4.5 预期收益的上界（诚实版）

设难任务层基线 `p=21.4%`，其中可被 GraspGuard 救回的比例为 `r`，误伤率为 `α`，则有：

`Δ* ≈ r·(1−p) − α·p − overhead`

若 `r=0.35`（35% 的失败是"空抓/滑移"且可重抓救回），`α=0.02`，则 `Δ* ≈ 0.35×0.786 − 0.02×0.214 ≈ 0.275 − 0.004 ≈ +27` 点（理想上界）。取保守实现率 50% ⇒ **+13.5 点**，正好落在可测区间。**这也是为什么主终点必须放在难任务层**：全局摊薄后只剩 +2.5 点。

## 5.5 命题与推导（P1–P7）

> 本节是**解析结果**，不是真机实测；用途是把"该不该做、要做多大"变成可复核的不等式。

**P1（样本量下界）** 设两臂独立、`p2 = p1 + δ`，双侧 α、功效 `1−β` 的两比例检验，每臂所需样本量满足

`n ≥ (z_{1−α/2} + z_{1−β})² · [p1(1−p1) + p2(1−p2)] / δ²`。

*证明*：H1 下方差近似 `[p1(1−p1)+p2(1−p2)]/n`，检验的非中心参数为 `δ / sqrt(var)`；要求其不小于 `z_{1−α/2}+z_{1−β}`，解出即得。∎
*推论*：取 `p1=0.25`、`α=0.05`、`power=0.8`，则 `n(+0.05)≈1248`、`n(+0.10)≈326`、`n(+0.15)≈150`。这正是"全局 +5 点不是 MVP 主终点"的算术原因。

**P2（分层增益）** 若效应只在占比 `f` 的任务上为 `δ`、其余为 0，则全局效应为 `fδ`；由 P1 的 `n ∝ 1/效应²`，`n_global / n_stratum = 1/f²`。
*证明*：`(δ/(fδ))² = 1/f²`。∎
*推论*：`f=6/32=0.1875 ⇒ 1/f²≈28.4`。**但反过来也成立**：若效应实际是弥散的，分层设计对"全局问题"反而是低功效的——这就是 R1 的数学形态。

**P3（合规乘性支配）** 记 `q = P(Conf=1)`，有效得分 `Score = q·p`。把成功率从 `p` 提到 `p+δ` 但有效概率降到 `q`，相对基线的净增益为

`Δ = q(p+δ) − p = δ − (1−q)(p+δ)`。

*正增益条件*：`1−q < δ/(p+δ)`。
*数值*：`p=0.214, δ=0.14 ⇒ 1−q < 0.395`。也就是说，仅"接口失效风险"就足以吃掉全部收益，且失效是**乘性归零**而非线性扣分 ⇒ **先体检、后能力**不是保守，而是最优排序。∎

**P4（保守介入的净收益；并修正上一轮 L3）** 记 `r` = 基线失败中"空抓/滑移且可救回"的比例，`α` = 把抓稳误判为空抓的假阳率，`h` = 干预的时间/扰动折损。则

`Δ = r(1−p) − α·p − h`。

*正增益条件*：`r(1−p) > α·p + h`。
*关键修正*：上一轮把"漏判（空抓没检出）"也计入伤害；但在 **S0 本身没有重抓逻辑** 的前提下，漏判的后果只是"退回基线"，**不会比基线更差**。真正的不对称是**假阳（打断一次好抓）+ 时间折损**。因此 MVP 可以采用极高阈值 `τ_hi`（假阳 ≤2%）而几乎不损失理论上界；这使 S1 比上一轮的 GraspVerify 更安全。
*数值*：`p=0.214, r=0.35, α=0.02, h=0.01 ⇒ Δ≈+0.261`；即便 `r` 只有 0.05，`Δ≈+0.025` 仍为正。真正的风险不是公式，而是 `r` 与伪标签质量不可知（R3/R7）。∎

**P5（单因子可识别性）** 若一次提交同时包含改动 1、2，观测到的 `Δ = δ1 + δ2 + δ12`；在 `δ12` 无独立估计时，`δ1` 不可识别。单因子提交（M7）把估计误差从"混淆偏差"降为"抽样噪声"。∎
*操作推论*：`S1 − S0` 只允许 `enable_guard` 一个开关差异；`τ_hi`、网络结构、训练种子必须在 A/B 前冻结，否则仍不可归因。

**P6（探针的信息价值）** 记协议变量 `X`（episode 预算、per-task 回传、chunk 语义、reset 边界、N）的熵为 `H(X)`，其下游一切 `n` 与判决都是 `X` 的函数。探针提交的成本为一个 slot `c`，收益是降低"实验规模设错 / 误杀真机制"的期望损失。当 `P(错误假设)` 不可忽略时，`EVSI(X) > c` 通常成立 ⇒ **先探针，后训练**。∎
*备注*：这不是严格定理，而是一个决策规则；它的可反驳形式是：若探针后 `protocol.json` 与提交前假设完全一致，则探针成本被浪费——但该事件的先验概率并不高。

**P7（安全监测的功效边界）** 用每任务每臂 `n_ctrl`、基线 `p_ctrl` 做伤害监测，其可检出的伤害下界由 P1 反解给出。取 `p_ctrl=0.30, n_ctrl=100, α=0.05, power=0.8`，则 `MDE≈17` 点：**控制层只能当"灾难探测器"，不能当 3–5 点的非劣性检验**。
*推论*：小伤害不能靠统计证明，只能靠**机制约束**（`τ_hi` 假阳 ≤2%、最多 2 次重抓、单 episode 干预 ≤6 s、任何不确定即回退）来上界；若要真做 5 点非劣性，控制层每任务需 ≈1000/臂，这在 MVP 预算内不可行——必须诚实标注，而不是假装测了。∎

### 6.1 服务（S1 = S0 + GraspGuard）

```python
import os
import time
import numpy as np


class UniBotMVP:
    """单 checkpoint、单 API；S1 与 S0 只差一个 GraspGuard 开关。"""

    def __init__(self, ckpt, enable_guard=True, tau_hi=0.90,
                 max_retry=2, budget_ms=105.0):
        self.policy = load_policy(ckpt)          # 冻结主干 + 单一动作头
        self.guard = GraspGuard() if enable_guard else None
        self.tau_hi = tau_hi
        self.max_retry = max_retry
        self.budget_ms = budget_ms
        self.sess = {}                           # port -> dict，严格隔离

    @property
    def metadata(self):
        return build_metadata()                  # §2.2 的模板

    def reset(self, port):
        self.sess[port] = {
            "last_a": None, "retry": 0, "t_close": None,
            "n_calls": 0, "deg": 0, "interventions": 0,
        }

    def get_action(self, obs, port):
        s = self.sess.setdefault(port, {
            "last_a": None, "retry": 0, "t_close": None,
            "n_calls": 0, "deg": 0, "interventions": 0,
        })
        s["n_calls"] += 1
        t0 = time.perf_counter()

        a = self.policy.act(obs, chunk=8)        # S0 基线动作块

        if self.guard is not None:
            p_empty = self.guard.empty_prob(obs)
            if self._should_intervene(s, obs, p_empty):
                a = self.guard.regrasp_block(a)  # 开→退→进→合，固定长度
                s["retry"] += 1
                s["interventions"] += 1

        s["last_a"] = a[-1]
        return self._wrap(a, t0, s)

    def _should_intervene(self, s, obs, p_empty):
        if s["n_calls"] < 3:
            return False
        if s["retry"] >= self.max_retry:
            return False
        if p_empty < self.tau_hi:
            return False
        if not gripper_closed(obs):
            return False
        if not phase_is_lift_or_transport(obs):
            return False
        return True

    def _wrap(self, a, t0, s):
        el = (time.perf_counter() - t0) * 1000.0
        degraded = el > self.budget_ms
        if degraded:
            a = repeat_last(a)
            s["deg"] += 1
        return {
            "meta.token": os.environ["UNIBOT_SUBMISSION_TOKEN"],
            "action.left_arm":  a["left_arm"].astype(np.float32),
            "action.right_arm": a["right_arm"].astype(np.float32),
            "action.left_gripper":  a["left_gripper"][:, None].astype(np.float32),
            "action.right_gripper": a["right_gripper"][:, None].astype(np.float32),
            "meta.degraded": degraded,
        }
```

> 说明：`build_metadata` / `gripper_closed` / `phase_is_lift_or_transport` / `repeat_last` 为占位，按官方 example 与实测字段实现；**未确认字段一律不输出**。

### 6.2 抓握伪标签

```python
        u = wrist_relative_displacement(episode["wrist_frames"], tc, t)

        if v < eps_v:
            continue                      # 没动过，信息量低
        if g < CLOSED_THRESH and u < eps_u:
            idx.append(t); labels.append(1); weights.append(1.0)
        elif u > eps_u:
            idx.append(t); labels.append(0); weights.append(1.0)
    return idx, labels, weights
```

### 6.3 校准与阈值选择

```python
def select_tau_hi(probs, labels, max_fpr=0.02):
    """在'抓稳'样本上限制假阳率，返回满足约束的最小阈值。"""
    pos = probs[np.asarray(labels) == 1]
    for tau in np.linspace(0.5, 0.999, 500):
        fpr = float((pos > tau).mean())
        if fpr <= max_fpr:
            return float(tau)
    return 0.999
```

### 6.4 分层 A/B 判决

```python
def decide(per_task):
    """
    per_task: {task: {"n0":..., "s0":..., "n1":..., "s1":...}}
    仅对 primary_tasks 合并；control 单独看。
    """
    delta, lo, hi = stratified_delta_ci(per_task["primary"], n_boot=10000)
    ctrl = pooled_delta(per_task["control"])
    ship = (lo > 0.0) and (ctrl >= -0.03)
    return {"delta": delta, "ci": (lo, hi), "ctrl": ctrl, "ship": ship}
```

## 11. 本轮最值得押注的与最大风险

**最值得押注**：**GraspGuard**——它用现有观测（腕部视觉 + 夹爪标量 + EE 运动）就能把"空抓 / 滑移"变成一个**高精度、可校准、可回退**的判定，并且是唯一一个预期效应能落在"可测区间（≥+10 点、集中在难任务层）"的机制。

**本轮最大风险（一句话）**：**如果 GraspGuard 的真实收益是弥散的小效应而非集中于难任务层的大效应，那么分层主终点会把一个真实的改进判成噪声并砍掉——MVP 会交付一个"跑得极稳、测得极准、但分数不足以竞争"的安全产品。**
