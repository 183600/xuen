# 第 13 轮（新灵感循环第 1 轮）· RUBRIC：官方 94 个评分点不是裁判，而是运行时技能图

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新灵感循环第 1 轮，三个词是「成功率」「失败恢复」「技能组合」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO；它把三者从「感知/控制层」推进到「评分层」：**官方 rubric 是运行时契约，技能事务是执行单元，180s 是预算，步骤分是第二目标。**

| 模型 | 成功率 | 步骤分 | 差 |
|---|---:|---:|---:|

| spirit/VLAGO | 25.9% | 34.4 | +8.5 |

如果步骤分只在任务成功时给，39.0 不可能大于 29.7。8 个模型全部呈现 **+6.9~+10.4** 的“步骤分溢价”。参赛手册也明确：**“超时记为失败，并根据执行情况计算步骤分，计入排名”**（2026-10-31 复核，CN 手册）。这不是猜测，而是官方计分规则。结论：

> **失败恢复的目标不只是把 0 变 1，还可以把 0.3 变 0.7；但排名先看成功率，所以必须先成功、后抢救，不能为了步骤分牺牲成功。**

官方 `tasks_v2/<slug>/info.json?v=2026-07` 把每个任务的 100 分拆成 2–5 个可读评分点（32 任务共 **94 步**），并给出难度、泛化说明、5 个示例 episode。这是本轮的核心新资产：**评分点不是赛后裁判，而是赛前就给出的运行时技能图。**

一句话押注：

> 把 94 个官方评分点编译成技能事务图；每个事务 = 执行 → 验证 → commit/rollback；失败时只重试失败的原子技能，不重跑整个任务；180s 内做“先成功、后步骤分”的字典序预算规划；用同一个 VLA 的 rubric 提示同时做执行和验证；用官方泛化说明做干扰脚本——不新增第二个学习模型，把一次 trial 变成多次机会。

三个灵感词怎么落地：

| 灵感词 | 落地 | 不做什么 |
|---|---|---|
| **成功率** | 原子级重试 + 技能组合 + 相关性/误报约束；`q(k)=1-(1-p)^k`，按 ρ 折减 | 不假设重试独立；不把 3 次重试当 3 倍成功率 |
| **失败恢复** | 技能事务 commit/rollback + 恢复原语 + 成功演示后缀检索 + 官方干扰脚本 | 不为每个任务训恢复策略；不新增学习 verifier |
| **技能组合** | 94 步 → 12 类技能；rubric step 是评分单元，原子技能是执行单元；单模型 step-conditioned 训练 | 不做 32 个任务各自的小模型；不把 rubric 当固定脚本 |

## 1. 本轮新核实的事实（只列会改变方案的）

### 1.1 官方 rubric：94 步、2–5 步/任务、每任务 100 分

`https://unibot.unitree.com/tasks_v2/<slug>/info.json?v=2026-07`（经 `r.jina.ai` 抓取；直接访问官网返回 **HTTP 567**；缓存 `Published Time: 2026-10-08`）逐任务给出：

- `scoring_points` / `scoring_points_en`：人类可读的评分点；
- `score_steps`：结构化 `{zh, en, score}` 数组；
- `difficulty_zh/en`：Easy 12 / Medium 12 / Hard 8；
- `generalization`：`unseen_object_3`、`human_1_note`、`human_4_note`；
- `episodes`：每任务 5 个示例 episode + 视频。

32 个任务合计 **94 个评分步**；每任务 2–5 步；每任务分值严格加和为 **100**。分步数分布：2 步 11 个任务、3 步 14 个、4 步 5 个、5 步 2 个。单步分值只有 20/25/30/40/50 五档；出现次数分别为 20×10、25×20、30×28、40×14、50×22。示例：HangCup 只有 2 步，抓杯把 50 分 + 挂到标记位置 50 分；ToolboxStorage 4 步各 25 分；FoldTowel 5 步各 20 分。

**对方案的含义**：官方已经把“任务”拆成了带分值的子目标。我们可以直接在运行时按评分点验证、提交、回滚、重试；不需要自己发明阶段划分或奖励。

### 1.2 官方计分规则确认“失败也有步骤分”

参赛手册（2026-10-31 复核；CN/EN 两版；`r.jina.ai` 抓取飞书）：

- 所有任务须基于**同一模型**完成，不得混合多个模型；模型类型不限。
- 通才模型赛道：32 任务，每任务 **10 次独立运行**；5 类泛化各 2 次（位置、干扰物、背景、未见物品、人为干扰）。
- 单次真机上限 **180s**；超时记失败；**根据执行情况计算步骤分，计入排名**。
- 排名：32 任务总平均成功率 → 总平均步骤分 → 更早提交。
- 另有**不计分的单任务测试通道**，可用于单任务成功率/步骤分验证。
- 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态隔离。

这解决了第 12 轮的一个关键不确定性：**步骤分不是只在成功时给，失败 trial 的执行进度也会被计分**。榜首 29.7% / 39.0 的差距与这条规则一致。

## 2. 诊断：三个断点

把一次失败拆开看：

```text
t0: 观测 → VLA 推理 → 返回 chunk
t0+0.1s: evaluator 开环执行 chunk
        ↑ 抓空、滑落、插偏、人移动物体都发生在这一段
t0+1.1s: 才看到下一帧 → 已经晚了
```

三个断点：

1. **不知道“哪一步失败了”**：全任务 VLA 只在任务级给动作，没有 rubric 级进度。失败后只能重跑整个任务，前面已完成的步骤白做。
2. **不会“只重试失败的那一步”**：即使知道失败，通常也是 reset 或 retry whole task；抓取失败后重新抓取、放偏后只重放，都是更便宜的原子重试。
3. **不为“步骤分”做决策**：排名先看成功率，但步骤分是第二排序键；当成功无望时，继续撞同一堵墙不如抢救独立评分点。官方已经按执行情况给步骤分，但现有方法没有显式优化它。

RUBRIC 对应三个断点：**rubric 级验证**、**原子级重试**、**预算化抢救**。

## 3. 方法：RUBRIC

**RUBRIC = Rubric-Using Budgeted Recovery and Inverse-skill Composition。**

### 3.1 总架构

```text
官方 32 × info.json
  │  score_steps / points / generalization / episodes
  ▼
Rubric Contract Compiler（离线）
  │  94 个评分步 → 12 类技能 → 原子技能 DAG
  │  每步：前置/后置条件、分值、可逆性、恢复集、语言 prompt、演示后缀索引
  ▼
Runtime Skill Transaction Manager（每端口一个，CPU 轻量）
  │  SELECT → PLAN → EXECUTE → VERIFY → COMMIT / ROLLBACK
  │  失败：恢复原语 + 同 VLA 恢复 prompt + 成功演示后缀检索
  ▼
Budgeted Retry & Salvage Planner（180s 字典序 DP）
  │  先最大化成功率；成功无望时最大化步骤分
  ▼
同一个 VLA（WLA-1.0 微调/基座）
  │  rubric step 同时作为执行 prompt 和验证 prompt
```

### 3.2 Rubric Contract Compiler：94 步 → 12 类技能

把 94 个评分步按动词/对象/目标映射到 12 类宏技能（子技能在括号里）：

| 宏技能 | 步数 | 典型子技能 | 典型任务 |
|---|---:|---|---|
| **PLACE** | 32 | place / rack / sort / adjust | FruitSorting、ColorArrangement、ArrangePlates |
| **PICK_PLACE** | 15 | pick+place / pick+return / pick+hang / pick+insert | FruitCollection、OrganizeTools、ArrangeTestTubes |
| **PICK** | 14 | grasp / bimanual hold / grasp+pull | HangCup S1、PlugCharger S1–S2、Unlock S1 |
| **CLOSE** | 8 | close / zip | ZipUp、PackBag、OrganizePencilCase |
| **DEFORM** | 5 | fold / straighten | FoldTowel |
| **EXTRACT** | 4 | unplug / pick out | DisconnectEthernet、PickOutBatteries |
| **OPEN** | 3 | open / zip open | PourOutMedicine、PlacePhotoFrame S2、OrganizePencilCase S1 |
| **LOCK** | 3 | lock / turn key / flip ring | Unlock、ToolboxStorage |
| **INSERT** | 3 | plug / soft insert | PlugCharger、PlugInEthernet、StorePaddle |
| **POUR** | 3 | pour / draw / inject | PourOutMedicine、SyringeWaterTransfer |
| **STACK** | 3 | stack | StackBowls、PaperCupStacking |
| **HANG** | 1 | hang | HangCup |

**可逆性统计**：94 步中 **89 步可逆**（R），**3 步不可逆**（I：倒药、抽水、注水），**2 步任务内实际不可逆**（I*：锁工具箱、拔图钉）。这意味着 **89/94 的步骤可以安全 rollback/retry**；只有 5 步需要“先确认、再执行”的保守策略。这是 RUBRIC 可行性的关键：恢复不是在所有地方都危险。

**两层技能图**：

- **评分层**（rubric step）：官方给分单元，2–5 个/任务，决定步骤分。
- **执行层**（atomic skill）：抓、移、放、插、挂、拧、拉、倒、折、按、拔等，决定重试粒度。

一个 rubric step 可能包含多个原子技能（例如 “Grab fruit 1 and put it into the basket” = PICK + TRANSPORT + PLACE）。**评分以 rubric step 为单位，重试以 atomic skill 为单位**：抓到了但放偏了，只重试 PLACE，不重新抓；这正是比“重跑整个任务”便宜的地方。

### 3.3 技能事务：执行 → 验证 → commit / rollback

每个原子技能是一个事务：

```text
EXECUTE  → 用 VLA/伺服执行 H 步
VERIFY   → 几何谓词 + 同 VLA 的 VLM yes/no（校准）
COMMIT   → 后置条件成立，记录 checkpoint，进入下一步
ROLLBACK → 后置条件失败/未知，退到最近 commit 的安全位姿，只重试本原子技能
```

关键设计：

- **commit point**：只有验证通过的步骤才 commit；失败步骤不污染后续步骤。
- **rollback target**：最近 commit 的安全位姿（桌面上方 5–10cm），不是初始位姿；避免把已完成的步骤推倒。
- **三值验证**：`pass / fail / unknown`；`unknown` 先执行“验证技能”（lift test、轻推、换个视角再看），不要立刻 rollback。
- **误报代价**：RESCUE（arXiv 2610.13516）已经证明 false alarm 会让恢复变差；所以只在 `P(fail)` 高且 `预期收益 > 回滚成本` 时干预。
- **不可逆步骤**：I/I* 步骤不做盲目 retry；先高置信验证，失败则 abort-safe + 抢救其他步骤。

### 3.4 预算化重试与步骤分抢救：先成功，后分数

设一个 rubric step 有 `k` 次尝试，单次成功率 `p`，则独立假设下 `q(k)=1-(1-p)^k`。但重试不是独立的；用 Beta-binomial 的相关性模型（ρ=0/0.3/0.6）折减：

| p=0.25 | k=1 | k=2 | k=3 | k=4 | k=5 |
|---|---:|---:|---:|---:|---:|
| ρ=0（独立） | 25.0% | 43.8% | **57.8%** | **68.4%** | 76.3% |
| ρ=0.3 | 25.0% | 38.1% | 46.5% | 52.3% | 56.7% |
| ρ=0.6 | 25.0% | 32.5% | 36.7% | 39.6% | 41.8% |

**结论**：重试有真实收益，但不是免费的；ρ 越高，收益越接近线性。必须先在小样本上估 ρ，不能承诺“3 次重试 = 3 倍成功率”。

预算分配用一个小型 DP/枚举（≤5 个 rubric step、每步 ≤3 个原子技能、180s）：

```text
状态：当前 step、剩余时间、各原子技能已尝试次数
动作：execute / retry / skip / salvage
目标（字典序）：
  1) 最大化任务成功率 ∏ Q_i
  2) 成功率相同，最大化步骤分 Σ w_i · P(reach_i) · Q_i
约束：Σ k_ij · c_ij ≤ 180s
```

一个说明性算例（p=0.25/步，c=15s/次，180s，3 步，分值 30/30/40，独立）：

| 策略 | 尝试次数 | 成功率 | 步骤分（顺序任务） | 步骤分（独立物体） |
|---|---|---:|---:|---:|
| 不重试 | (1,1,1) | 1.6% | 10.0 | 25.0 |
| 每步 2 次 | (2,2,2) | 8.4% | 22.2 | 43.8 |
| 成功优先 | (4,4,4) | **31.9%** | **47.3** | **68.4** |
| 对象 1 不可恢复，抢救 2/3 | (0,6,6) | 0% | 0.0（不可达） | **57.5** |

最后一行是“步骤分抢救”：当成功已无望时，不要再把 180s 全砸在不可恢复的对象 1 上；把时间给独立的对象 2/3，仍能拿 57.5 分。步骤分是第二排序键，这就是它的价值。

**在线更新**：每个原子技能用 Beta(1+success, 1+failure) 更新 `p`；单任务通道的 5 次结果只用来粗调，不用来宣称涨点。320 trials 在 p≈0.25 时 SE≈2.42pp，+1–2pp 不能当结论。

### 3.5 同一个 VLA 的 rubric 双用：执行 + 验证

RUBRIC 不新增学习 verifier。官方评分点本身就是自然语言，可以**同时**用于：

- **执行 prompt**：`"Step 2/3: Place the red block in the rightmost position."`
- **验证 prompt**：`"Is the red block in the rightmost position? Answer yes or no."`

同一个 WLA/VLM checkpoint，同一个视觉编码器；只是问题模板不同。每个评分步验证 1–2 次（每任务 ≤10 次），延迟可摊薄。做法：

1. 用成功演示的终态做正样本，用“步骤开始前/物体被移走/只完成一半”的状态做负样本，校准 yes/no 的 logit 阈值。
2. 组合几何谓词（颜色/形状/相对位姿/夹爪状态/升降测试）与 VLM yes/no；两者都过才 commit，都不过才 rollback，冲突则 `unknown` → 验证技能。
3. 对透明/反光/可变形物体（锁、瓶、毛巾），VLM 语义验证比纯几何更稳；对位置/插入，几何更稳。两者互补。

这是“单模型合规”的关键：**验证不是第二个模型，而是同一个模型的另一种提问方式。**

### 3.6 官方干扰脚本 + 成功演示后缀检索

**官方干扰脚本**：把 `generalization` 的 30 组 `human_1/human_4` 说明编译成恢复规则。例如：

| 官方说明 | 运行时检测 | 恢复 |
|---|---|---|
| 杯子向后/向右 | 杯子相对初始位姿位移 | 重定位 → 重新接近 → 重抓 → 重挂 |
| 锁向左移动 / 中途把锁拿走 | 锁位移/消失 | 重定位；若被拿走 → WAIT/抢救 |
| 拉上拉链之后拉开 | 拉链滑块回退/开口 | 重拉 |
| 叠完毛巾翻开 | 毛巾折叠状态变化 | 重叠 |
| 插头拔起 | 插头相对插座位移 | 重插 |
| 盖子拧回 | 瓶盖角度回退 | 重开 |
| 笔盒合上后打开 | 笔盒开合状态变化 | 重关 |
| 第二个碗被拿掉 | 碗堆高度/数量变化 | 重叠 |

这些脚本是确定性的，不需要学习；它们直接利用官方会执行的干扰。人为干扰占每任务 10 次中的 2 次（20%），如果能把这类 trial 的成功率从 20% 提到 50%，平均成功率就有约 **+6pp** 的空间（0.2×30pp）。这是本轮最“竞赛特定”的杠杆。

**成功演示后缀检索**：从 33k 成功演示里，为每个原子技能建索引：

- 技能类型、物体/目标类别、夹爪状态、相对 EE 位姿、腕部图像局部特征；
- 该技能从当前状态到成功的动作后缀（相对 EE 增量 + 夹爪）。

失败时，检索最近的成功状态，回放其**相对动作后缀** H 步；若不可用，退回恢复原语/VLA 恢复 prompt。它不训练新模型，只是把“成功演示”变成“恢复先验”。

### 3.7 单模型 step-conditioned 训练（可选增强）

如果时间允许，把 33k 演示按 rubric step 切段，用**同一个 WLA** 做 step-conditioned 微调：

- 冻结 VLM，只训 DiT action head + robot-state projector（官方 24GB 配方）；
- 输入 = 当前观测 + `"Step i/n: <rubric step>"`；输出 = 30 步动作 chunk；
- 目标 = 动作损失 + 可选的 step-boundary/progress 辅助（同一个模型，不加第二个网络）；
- 运行时由事务管理器设置当前 step prompt，实现“一个模型 + 12 类技能”的组合。

这仍然是**一个 checkpoint**；不是 32 个任务各训一个模型。它的价值是把“任务级语言”细化成“评分点级语言”，让同一个模型在跨任务共享技能时更稳。

## 4. 与近期工作的差异（一句话版）

- **LOGIV**：也有任务图 + 局部修复，但图是规划器生成的，不读官方 rubric；不优化步骤分/180s 预算。我们加的是**官方评分点契约 + 原子级预算重试 + 抢救**。
- **RoboDuo**：也用原子技能补完，但需要第二个 atomic VLA + coding agent；单模型合规风险高。我们只用**一个 VLA + 确定性事务层**。
- **SafeLoop / VLA-Corrector / Backtrack / FLARE**：都加学习式风险头/verifier/reset 技能；我们不加学习组件，用**同 VLA 的 rubric 双用 + 几何谓词**。
- **ProbeAct**：训练-free 的抓取/放置恢复，但不读官方 rubric、不做步骤分。我们把恢复扩展到**12 类技能 + 94 个评分点**。
- **FAR / CARE**：要 test-time 更新或失败数据；我们用**成功演示后缀 + 官方干扰脚本**，不需要失败数据。
- **CycleVLA**：VLM 失败预测 + MBR；我们用**官方 rubric 验证 + 预算 DP**，不做 test-time scaling。

## 7. 风险与合规

| 风险 | 说明 | 缓解 |
|---|---|---|
| **验证器误报** | 把成功判失败 → 回滚破坏进度 | 三值逻辑 + 高阈值 + 验证技能 + 代价敏感 |
| **evaluator 终止语义** | 若“失败”立即终止，trial 内重试无效 | 单任务通道先测；只对非终止子失败重试 |
| **重试相关性** | ρ 高时收益远低于独立假设 | 小样本估 ρ；按保守值规划 |
| **不可逆步骤** | 倒药/抽水/注水/锁箱/拔钉 | 5/94 步；先验证再执行，失败 abort-safe |
| **人为干扰安全** | 人手进入工作空间 | 暂停/等待/避让；不与人抢物体 |
| **单模型合规** | 任何额外学习模型都可能违规 | C1：纯确定性；C2：同 checkpoint VLM；不做 C3 |
| **延迟** | VLM 验证 + 事务层增加延迟 | 只在 step 边界验证；CPU 决策；p99≤150ms |
| **数据标注** | 94 步切段/验证器工作量大 | 先做 61 个 PICK/PLACE 步；其余用 VLM 兜底 |

## 2. 问题形式化

### 2.1 指标

32 个任务，每任务 10 次独立运行。设任务 `t` 的成功率为 `p_t`，平均成功率为：

```text
S = (1/32) Σ_t p_t
```

排名先比 `S`；相同再比平均步骤分：

```text
P = (1/32) Σ_t (1/10) Σ_{r=1}^{10} score_{t,r}
```

`score_{t,r} ∈ [0,100]` 是该次运行按 `score_steps` 累计的得分；失败/超时也可能有部分分（手册 A 级规则）。因此目标函数是字典序：

```text
maximize (S, P, -submission_time)
```

**关键含义**：步骤分不是第一目标；不能在成功仍有可能时为了步骤分放弃成功。抢救模式只在“成功概率低/预算不足/步骤不可恢复”时启用。

### 2.2 预算与重试

单次 trial 上限 `B=180s`。设原子技能 `j` 的单次成本 `c_j`、单次成功率 `p_j`、尝试次数 `k_j`。独立假设：

```text
q_j(k_j) = 1 - (1 - p_j)^{k_j}
```

相关性折减：用 Beta-binomial，`X ~ Beta(a,b)`，`a=p(1-ρ)/ρ`，`b=(1-p)(1-ρ)/ρ`：

```text
q(k) = 1 - E[(1-X)^k] = 1 - B(a, b+k)/B(a,b)
```

`ρ=0` 退化为独立。p=0.25 的表：

| k | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|
| ρ=0 | 25.0% | 43.8% | 57.8% | 68.4% | 76.3% |
| ρ=0.3 | 25.0% | 38.1% | 46.5% | 52.3% | 56.7% |
| ρ=0.6 | 25.0% | 32.5% | 36.7% | 39.6% | 41.8% |

**结论**：重试有真实收益，但 ρ 越高越接近线性；必须在小样本估 ρ，不能承诺“3 次重试 = 3 倍成功率”。

### 2.3 技能契约图

对每个任务 `t`，构造有向图 `G_t=(V_t,E_t)`：

- `v ∈ V_t`：一个官方评分步（94 个之一）。
- 属性：`id`、`desc`、`points`、`preconditions`、`postconditions`、`verifier`、`reversible`、`recovery_set`、`language_prompts`、`demo_suffix_index`。
- `e=(u,v)`：`u` 必须在 `v` 前完成（例如抓杯 → 挂杯；开盖 → 倒药；放稳 → 拉链）。
- 独立对象步（水果 1/2/3、盘子 1/2/3）之间无边，可重排。

每个评分步再分解为原子技能序列 `v = (a_1,...,a_m)`，例如：

```text
"Grab fruit 1 and put it into the basket"
  = PICK(fruit1) → TRANSPORT(fruit1, basket) → PLACE(fruit1, basket) → VERIFY
```

**评分以 `v` 为单位，重试以 `a_j` 为单位**。这是 RUBRIC 与“重跑整个任务”的核心区别。

### 2.4 两层 MDP

- **上层（评分层）**：状态 = 已 commit 的评分步集合、剩余时间、各步尝试次数；动作 = 执行/重试/跳过/抢救；奖励 = 成功率（第一目标）/步骤分（第二目标）。
- **下层（执行层）**：状态 = 当前原子技能、EE/夹爪/物体状态；动作 = VLA chunk/伺服/恢复原语；奖励 = 原子技能后置条件成立。

上层用 DP/枚举（≤5 步、≤3 原子技能、k≤10）；下层用事务管理器 + 验证器。两层解耦，便于工程实现。

### 2.5 假设

- evaluator 在子目标失败后继续执行，直到任务成功/终止失败/180s；**待 G0 验证**。
- 步骤分按评分点累计；失败 trial 的部分完成计分；**手册 A 级，具体归一化待验证**。
- 控制频率 30Hz；chunk 5 步 ≈167ms；**待测**。
- 同一任务 10 次运行的初始状态/泛化类型固定；**待测**。
- 官方 WLA 可微调/推理；24GB GPU 可跑；**待测**。

### 3.6 演示切段

从 33k 成功演示切出原子技能段：

1. **夹爪事件**：开→闭 = grasp；闭→开 = release；连续闭合 + 位置变化 = transport。
2. **物体运动**：物体相对 EE/桌面的位移、速度、加速度；用于分段和验证器阈值。
3. **语言对齐**：任务级语言 + rubric step 文本；按目标对象/目标区域匹配。
4. **人工复核**：94 步 × 代表性演示（每步 3–5 条）；其余用规则自动切。
5. **输出**：`(task, step, frame_start, frame_end, skill, object, target, relative_pose, action_suffix)`。

**标注成本**：94 步人工复核 1–2 天；自动切段 + QA 1 周。难点：可变形（毛巾）、多物体（工具箱/文具）、透明/反光（锁/瓶）。

### 3.7 验证器库

每个原子技能一个三值验证器（pass/fail/unknown）：

| 技能 | 信号 | pass 条件 | 备注 |
|---|---|---|---|
| PICK/grasp | 夹爪闭合 + 物体随手移动 + 腕部图 | lift test 后物体仍在手 | 抓空/滑落检测 |
| PLACE | 头双目/腕部目标区域 + 夹爪开 + 释放后稳定 | 物体在目标区域内 + 静止 | 颜色/形状/相对位姿 |
| INSERT | 相对位姿 + 轻拉不脱 + 视觉插入 | 连接器到位 + 轻拉稳定 | 插头/网线/试管 |
| HANG | 杯把/挂点相对位姿 + 释放 + 重力 | 释放后不掉 | 可做 lift test |
| STACK | 相对位姿 + 释放后稳定 | 上层在下层上 + 不滑 | 碗/杯 |
| OPEN | 盖/拉链/锁角度变化 + 内容可见 | 角度/位移超阈值 | 透明物体用 VLM |
| CLOSE | 盖/拉链闭合 + 无缝隙 | 闭合到位 | 可用 VLM |
| ZIP | 拉链滑块到端点 + 布面闭合 | 滑块到位 | 可变形 |
| LOCK | 钥匙角度 + 锁体状态 | 开/锁到位 | 反光，VLM 辅助 |
| POUR | 瓶/针管倾斜 + 目标容器内容变化 | 内容转移 | 液体不可逆 |
| DEFORM | 角/边对齐 + 折叠次数 | 形状匹配 | 毛巾/文具袋 |
| EXTRACT | 物体离开容器 + 其他物体未动 | 目标物体取出 | 电池/网线/图钉 |

**同 VLA 的 VLM 双用**：

```text
执行 prompt: "Step 2/3: Place the red block in the rightmost position."
验证 prompt: "Is the red block in the rightmost position? Answer yes or no."
```

同一个 checkpoint；每个评分步验证 1–2 次（每任务 ≤10 次）。校准：成功演示终态为正样本；步骤开始前/物体被移走/半完成为负样本；用 yes/no logit 阈值，要求 precision≥0.9、recall≥0.8、false alarm≤5%。

**代价敏感**：RESCUE 证明 false alarm 会让恢复变差。只在 `P(fail)>τ` 且 `预期收益>回滚成本` 时干预；`unknown` 先做验证技能，不立刻 rollback。

离线索引：

```text
key   = (task, step, skill, object_class, gripper_state, relative_pose_bin)
```

- 特征：物体/目标相对 EE 位姿、夹爪开合、颜色/形状直方图、腕部局部特征；C2 可用同 VLM 图像 embedding。

## 4. Runtime Skill Transaction Manager

### 4.1 端口/进程拓扑

```text
evaluator ── 8765 ── PolicyService(port 0) ── STM 0 ── VLA client ── GPU model server
          ── 8766 ── PolicyService(port 1) ── STM 1 ── VLA client ── (shared queue)
          ── ...
          ── 8765+N-1
```

- 每端口一个独立 `PolicyService` + `STM`，独立 `reset()` 状态。
- VLA 推理可共享一个 GPU 模型服务器，但要限流/排队；恢复层纯 CPU。
- 每端口维护：当前任务、rubric DAG、已 commit 步骤、checkpoint 位姿、尝试次数、剩余时间、验证器状态。
- 不使用跨端口共享的可变状态；只共享只读 rubric 配置/演示索引。

### 4.2 状态机

```text
RESET
  → SELECT_STEP（选下一个 ready 评分步）
  → PLAN（原子技能序列 + 预算）
  → EXECUTE（VLA/伺服 H 步）
  → VERIFY（几何 + VLM）
      ├─ pass → COMMIT → 下一步/任务成功
      ├─ fail → ROLLBACK → RECOVER → 重试/跳过/抢救
      └─ unknown → VERIFY_SKILL → 再判
  → SALVAGE（成功无望时抢救独立评分点）
  → DONE（成功/终止/超时）
```

### 4.3 `get_action` 伪代码

```python
def get_action(self, obs):
    self._update_time(obs)
    if self._need_reset(obs):
        self._reset_episode(obs)

    # 1) 若当前 rubric step 未完成，执行其下一个原子技能
    if self.current_atom is not None:
        if self._atom_done(obs):
            self._commit_atom()
        elif self._atom_failed(obs):
            self._rollback_and_recover(obs)
        else:
            return self._vla_chunk(obs, self.current_atom)

    # 2) 若当前 rubric step 完成，commit 并选下一步
    if self.current_step is not None and self._step_done(obs):
        self._commit_step()
        self.current_step = None

    # 3) 选下一个 ready step（依赖满足、预算允许）
    self.current_step = self._select_step(obs)
    if self.current_step is None:
        return self._salvage_or_hold(obs)

    # 4) 规划原子技能 + 预算
    self.current_atom = self._next_atom(self.current_step, obs)
    self.plan = self._retry_planner.plan(
        self.rubric, self.current_step, self.history,
        time_left=self.time_left, rho=self.rho_estimate
    )

    # 5) 返回 5 步 chunk（内部可预测 30 步，只执行前 5 步）
    return self._vla_chunk(obs, self.current_atom)
```

`_vla_chunk` 返回 `action_chunk_size=5` 的动作；模型内部仍可预测 30 步，取前 5 步执行。恢复层在每个 chunk 后重新观测。

### 4.4 Commit / rollback

- **checkpoint**：每次 commit 记录 `(joint_pos, ee_pose, gripper, rubric_step, time)`。
- **rollback target**：最近 commit 的安全位姿（桌面上方 5–10cm），不是初始位姿；避免推倒已完成步骤。
- **rollback path**：先抬升到安全高度，再关节空间插值到目标；用头双目检查桌面障碍。
- **不可逆步骤**：I/I* 步骤 commit 前必须高置信验证；失败则 `ABORT_SAFE` + `SALVAGE`，不 rollback。
- **误报保护**：`fail` 需要两次独立证据（几何 + VLM 或两次观测）；单次低置信 fail 只触发 `VERIFY_SKILL`。

### 4.5 原子重试循环

```text
attempt = 0
while attempt < k_max and time_left > c_atom:
    execute(atom)
    verdict = verify(atom)
    if verdict == PASS:
        commit(atom); break
    if verdict == FAIL:
        rollback_to_last_commit()
        recover(atom, failure_mode)
    else:  # UNKNOWN
        run_verification_skill(atom)
    attempt += 1
if not committed:
    handle_step_failure(atom)
```

### 4.6 恢复原语

| 原语 | 作用 | 适用失败 | 成本 |
|---|---|---|---|
| `RETREAT(d)` | 沿接近轴后退 3–10cm | 插偏/碰撞/夹爪缠绕 | 低 |
| `REALIGN(target)` | 重新观测，修正相对位姿 | 对不准/目标移动 | 低 |
| `REGRASP(pose/hand)` | 开爪、退、换抓取位姿/手 | 抓空/滑落 | 中 |
| `RELEASE` | 开爪释放 | 放不下/缠绕 | 低 |
| `REOBSERVE(view)` | 移动头/腕到更好视角 | 遮挡/不确定 | 低 |
| `WAIT(t)` | 保持，等待人离开/物体稳定 | 人为干扰/动态 | 低 |
| `REPLAN(prompt)` | 同 VLA + 恢复 prompt | VLA 走偏 | 中 |
| `VERIFY_SKILL` | lift/wiggle/轻推/再看 | 验证不确定 | 低 |
| `SKIP` | 跳过独立步骤 | 不可恢复/预算不足 | 0 |
| `ABORT_SAFE` | 退出到安全位姿 | 不可逆/危险 | 低 |

### 4.7 失败分类

| 失败 | 检测 | 恢复 |
|---|---|---|
| MISSED_GRASP | 夹爪闭合但 lift test 物体不动 | REGRASP + REALIGN |
| SLIP_DROP | 物体相对夹爪位移/掉落 | RELOCALIZE + REGRASP；掉桌下 → ABORT_SAFE |
| MISALIGN | 接触但无进展/反复卡住 | RETREAT + REALIGN + 慢插 |
| WRONG_OBJECT/TARGET | VLM/几何与 rubric 不符 | REGROUND + REPLAN |
| OCCLUSION | 目标不可见/低置信 | REOBSERVE + WAIT |
| HUMAN_DISTURBANCE | 物体位移/消失/被还原 | 官方脚本（§3.9） |
| COLLISION/STALL | 关节误差/速度异常 | RETREAT + REPLAN + 降速 |
| IRREVERSIBLE | 液体/锁/图钉 | ABORT_SAFE + SALVAGE |
| PARTIAL | 部分评分步完成 | CONTINUE 或 SALVAGE |
| TIMEOUT | 无进展/时间不足 | SALVAGE |

### 4.8 同 VLA 恢复 prompt

模板（按失败模式选择，不训练新模型）：

```text
"The grasp missed the cup handle. Retreat 5 cm and grasp the handle from the left."
"The plug is not aligned with the socket. Move back 3 cm, align, and insert slowly."
"The human moved the cup backward. Re-localize the cup, approach it, and hang it."
"The zipper was opened after zipping. Straighten the pouch and zip it again."
"The bowl was removed from the stack. Re-localize the bowl and stack it again."
```

恢复 prompt 与 rubric step prompt 拼接；VLA 仍输出 30 步，执行前 5 步。

### 4.9 演示后缀检索恢复

```text
query = (skill, object_class, gripper_state, relative_pose)
candidates = index.search(query, k=5)
for c in candidates:
    if compatible(c, current_scene):
        replay(c.action_suffix[:H])
        if verify(atom) == PASS: return PASS
return REPLAN(prompt)
```

检索失败/不兼容 → 恢复原语 → VLA prompt。三层回退，保证不会卡死。

### 4.10 人为干扰处理

1. **检测**：物体位移/消失/状态回退（拉链/盖子/折叠/堆叠）；与机器人动作无关的变化。
2. **安全**：检测到人手进入工作空间 → 暂停/后退/等待，不与人抢物体。
3. **恢复**：按官方脚本（§3.9）执行；若物体被拿走且未返回 → WAIT 一段时间后 SALVAGE。
4. **防止重复**：同一干扰只处理一次；记录已恢复的干扰，避免循环。

### 4.11 安全与不可逆

- 5/94 步不可逆/实际不可逆：倒药、抽水、注水、锁箱、拔图钉。
- 这些步骤：先高置信验证前置条件；执行时降速；失败不 rollback，直接 ABORT_SAFE + SALVAGE。
- 人手/碰撞：优先暂停/后退；安全高于步骤分。
- 物体掉落桌下：不伸手去桌下；ABORT_SAFE。

### 4.12 延迟预算

| 模块 | 频率 | 预算 |
|---|---|---|
| VLA 推理 | 每 5 步 | 100–300ms（取决于模型/网络） |
| 事务决策 | 每 chunk | ≤10ms CPU |
| 几何验证 | 每 step | ≤30ms CPU/GPU |
| VLM yes/no | 每评分步 1–2 次（≤10/任务） | 100–300ms |
| 恢复原语 | 失败时 | ≤50ms 规划 + 执行 |
| 预算 DP | 每次失败/step | ≤10ms（≤5 步枚举） |

恢复层的 p99 目标 ≤150ms（不含 VLA 推理）；每任务额外 ≤3s（≤10 次 VLM 验证），相对 180s 可忽略。

## 5. 预算化重试与步骤分抢救规划

### 5.1 DP 形式化

对任务 `t`，评分步 `i=1..n`，原子技能 `j=1..m_i`，尝试次数 `k_ij`：

```text
Q_i = ∏_j q_ij(k_ij)                  # 评分步完成概率
P_success = ∏_i Q_i                   # 顺序任务；独立对象可交换
E[score] = Σ_i w_i · P(reach_i) · Q_i
time = Σ_ij k_ij · c_ij ≤ B
```

- 顺序任务：`P(reach_i)=∏_{l<i} Q_l`。
- 独立对象：`P(reach_i)=1`，`E[score]=Σ_i w_i Q_i`。
- 目标：字典序 `max (P_success, E[score])`。
- 求解：枚举 `k_ij`（≤5 步、≤3 原子、k≤10）或 DP；离线算策略表，在线用 Beta 后验更新 `p_ij` 后重算。

3 步、p=0.25/步、c=15s/次、B=180s、分值 30/30/40：

| 策略 | 尝试 | 成功率 | 步骤分（顺序） | 步骤分（独立） |
|---|---|---:|---:|---:|
| 不重试 | (1,1,1) | 1.6% | 10.0 | 25.0 |
| 每步 2 次 | (2,2,2) | 8.4% | 22.2 | 43.8 |
| 成功优先 | (4,4,4) | **31.9%** | **47.3** | **68.4** |
| 对象 1 不可恢复，抢救 2/3 | (0,6,6) | 0% | 0.0（不可达） | **57.5** |

相关性折减（同样 (4,4,4)）：

| ρ | 成功率 | 步骤分（顺序） | 步骤分（独立） |
|---|---:|---:|---:|
| 0 | 31.9% | 47.3 | 68.4 |
| 0.3 | 14.3% | 29.6 | 52.3 |
| 0.6 | 6.2% | 19.1 | 39.6 |

**解释**：重试收益受相关性强烈影响；抢救模式在“成功无望”时仍能拿 57.5 分。**不要用独立假设做承诺；先用单任务通道估 ρ。**

### 5.4 在线估计

- 每个原子技能维护 `Beta(α,β)`，初始 `α=1, β=1` 或从演示/单任务先验。
- 每次 attempt 更新；用后验均值 `p=α/(α+β)` 和方差估计 ρ（同一技能连续失败的相关性）。
- 单任务通道每次 5 次，统计功效低；只做粗调/淘汰，不做最终结论。
- 全量 320 trials：p≈0.25 时 SE≈2.42pp；+5pp 约 2 SE，需配对/多看任务。

### 5.5 字典序策略

```text
if P_success(still_reachable) > ε and time_left >= c_min:
    optimize success (retry prerequisites/high-impact atoms first)
else:
    optimize step score (independent high-point steps first)
```

- `ε` 由剩余时间、可恢复步数、后验 p 估计；建议 `ε=0.05` 起步。
- 成功模式：优先重试“瓶颈原子”（下游依赖多、p 低）；不要为了抢救跳过关键前置。
- 抢救模式：先做独立高分组；不可恢复步 `SKIP`；避免在 I/I* 步浪费预算。
- 任何模式：I/I* 步失败 → ABORT_SAFE，不进抢救循环。

### 5.6 相关性与误报

- **相关性**：模型偏差导致的失败（同一抓取位姿反复失败）ρ 高；人为干扰/物体移动导致的失败 ρ 低。按失败类型分别估 ρ。
- **误报**：验证器 false alarm 会触发不必要 rollback；用高阈值 + 二次证据 + 代价敏感。RESCUE 的结论：monitor 准确不等于干预有价值；我们优化的是干预收益，不是 detector AUC。
- **漏报**：false negative 会让错误步骤 commit，污染后续；用 commit 前的 lift/轻推验证降低漏报。

### 5.7 320 trials 的竞赛分配

| 泛化类型 | 每任务次数 | 占总 trials | 可用的官方先验 | 策略 |
|---|---:|---:|---|---|
| 位置 | 2 | 20% | 5 个示例 + 通用重定位 | 相对位姿/腕部伺服 |
| 干扰物 | 2 | 20% | 5 个示例 | 类别无关抓取/目标检测 |
| 背景 | 2 | 20% | 5 个示例 | 颜色/几何鲁棒 |
| 未见物品 | 2 | 20% | `unseen_object_3` 23/32 | 类别/颜色无关 prompt |
| 人为干扰 | 2 | 20% | `human_1/human_4` 30/32 | 官方干扰脚本 |
| 合计 | 10 | 100% | 160 个示例视频 | — |

**杠杆**：人为干扰 20% 的 trials；若该类从 20%→50%，平均成功率 +6pp。未见物品 20%；类别无关策略可防回归。步骤分抢救只在成功低的任务上启用，避免影响成功优先。

> 注：表中“5 个示例”按 §1.6 的 C 级假设（5 示例对应 5 类泛化）填写；若核实失败，则只把 160 个视频当成功/近成功样例，不影响恢复脚本。

### 5.8 单任务通道协议

1. 选 10 个高价值任务（覆盖 PICK/PICK_PLACE/PLACE/HANG/INSERT/ZIP/LOCK/STACK）。
2. 每任务 5 次基线 + 5 次 RUBRIC；同一初始状态/泛化类型（若可控）。
3. 记录：成功率、步骤分、失败模式、验证器判定、重试次数、耗时。
4. 决策：≥+1/5 且步骤分不降 → 进入下一轮；否则回滚该模块。
5. 不做“5 次涨 1 次就宣称 +20pp”的结论；用配对/多任务聚合。

### 5.9 统计功效

- 320 trials，p≈0.25：SE≈2.42pp；95% CI 约 ±4.7pp。
- 单任务 10 trials：SE≈13.7pp（p=0.25）；几乎不能单独判断 +5pp。
- 因此：单任务通道用于**调试/淘汰**，全量用于**结论**；需要 paired seeds/固定初始态来降方差（若评测支持）。

## 6. 单模型 step-conditioned 训练（可选增强）

### 6.1 数据切段/标签

- 用 §3.6 的切段输出，把每帧标到 `(task, rubric_step, atomic_skill)`。
- 语言输入：`"Step i/n: <rubric step>"`；可拼接任务级描述。
- 多物体任务：每对象一个 step 实例；共享同一 rubric step 文本 + 对象索引。
- 语言增强：HangCup 的 5 条改写；其余任务下载 `tasks.parquet` 后同样处理；模板化改写（不改语义）。

### 6.2 模型/冻结

- 基座：UnifoLM-WLA-1.0-Base（6B）。
- 冻结 VLM（`qwen_vl_interface`）；训练 DiT action head + robot-state projector。
- 输入：`cam_left_high` + 左右腕部三图 + 60D state + step prompt。
- 输出：30 步 54D action chunk；挑战赛适配层取前 5 步/映射到 21D。
- 可选 LoRA：VLM 语言侧 LoRA，提升 step prompt 理解；仍是一个 checkpoint。

### 6.3 目标

```text
L = L_action (flow/diffusion) + λ1 L_step_boundary + λ2 L_progress
```

- `L_action`：官方 WLA 动作损失。
- `L_step_boundary`/`L_progress`：可选辅助头（同一个模型），预测当前 rubric step/进度；用于验证器置信度，不替代几何验证。
- 不加第二个网络；辅助头与 action head 共享 backbone。

### 6.4 语言增强

- 5 条任务改写（HangCup 已验证）。
- Rubric step 改写模板：`"Grab the X" / "Pick up the X" / "Take the X"`。
- 对象/目标同义词：颜色/形状/类别，避免过拟合单一词。
- 干扰脚本语言：`"The cup moved backward; re-localize and hang it."` 作为恢复 prompt 训练（可选）。

### 6.5 算力/时间

- 单张 24GB GPU 可微调（官方配方）；33k episodes/18M frames 需要多 epoch 不现实，建议 1–2 epoch 或子采样。
- 数据转换（HF → WLA 格式）1–2 周；训练 3–7 天/轮；推理优化（chunk 5、缓存）1 周。
- 如果时间不够：**跳过训练，直接用基座 + 事务层**；MVP 不依赖训练。

### 6.6 合规

- 一个 checkpoint；step prompt 是输入，不是新模型。
- 辅助头属于同一模型；若官方对“模型”严格按 checkpoint 计，仍合规。
- C1（纯确定性）不需要训练；C2（同 VLM 验证）也不需要新 checkpoint；C3（外部检测器）不做。

## 7. 技能组合与迁移

### 7.1 12 类技能覆盖矩阵

| 技能 | 评分步数 | 代表任务 |
|---|---:|---|
| PICK | 14 | HangCup、PlugCharger、Unlock、PackBag |
| PICK_PLACE | 15 | FruitCollection、FruitSorting、OrganizeTools、ArrangeTestTubes |
| PLACE | 32 | 几乎所有任务 |
| STACK | 3 | StackBowls、PaperCupStacking |
| HANG | 1 | HangCup |
| INSERT | 3 | PlugCharger、PlugInEthernet、StorePaddle |
| EXTRACT | 4 | DisconnectEthernet、PickOutBatteries、RemovePinnedNote |
| OPEN | 3 | PourOutMedicine、OrganizePencilCase、PlacePhotoFrame |
| CLOSE | 8 | ZipUp、PackBag、ToolboxStorage、PackPhone |
| LOCK | 3 | Unlock、ToolboxStorage |
| POUR | 3 | PourOutMedicine、SyringeWaterTransfer |
| DEFORM | 5 | FoldTowel |

**含义**：32 个任务不是 32 种技能，而是 12 类技能的重复组合；单模型 step-conditioned 训练 + 运行时组合是可行的。

### 7.2 运行时组合

```text
Task = DAG of rubric steps
rubric step = sequence of atomic skills
atomic skill = VLA chunk + verifier + recovery
```

事务管理器按 DAG 选 ready step；每步用 rubric prompt 调 VLA；验证通过 commit；失败只重试原子技能。

### 7.3 跨任务迁移

- 同一技能在不同任务共享：抓取、放置、插入、拉链、开盖、堆叠。
- 训练时混合 32 任务，按技能平衡采样；避免 Easy 任务主导。
- 运行时 prompt 用 rubric step 文本，不用任务名；鼓励技能级泛化。
- 未见物体：用类别/颜色无关 prompt + 几何验证；不要依赖固定物体名。

### 7.4 逆技能组合

给定评分点后置条件，反推最小原子技能序列：

```text
postcondition "cup_handle_on_rack"
  → HANG(cup, rack) = PICK(handle) + TRANSPORT(rack) + ALIGN + RELEASE + VERIFY
postcondition "plug_in_socket"
  → INSERT(plug, socket) = PICK(plug) + ALIGN + PUSH + VERIFY
postcondition "zipper_closed"
  → ZIP(pouch) = PICK(tab) + PULL + VERIFY
```

这就是“inverse-skill composition”：从官方评分点反推技能，而不是让 VLA 自由发挥。

### 7.5 例子

**HangCup**：PICK(handle) → HANG(rack)；失败：抓空 → REGRASP；挂偏 → REALIGN/REHANG；杯子被移动 → 重定位。

**FruitSorting**：3 个独立 PICK_PLACE；每个水果是一个评分步；失败只重试该水果；成功无望时先做高分水果。

**ToolboxStorage**：PLACE(tools)×2 → CLOSE(lid) → LOCK；锁是不可逆 I*，最后做；前面失败可 rollback。

**ZipUp**：PLACE(adjust pouch) → CLOSE(zip)；人拉开 → 重拉；拉链卡住 → RETREAT + REALIGN + 慢拉。

| 门 | 问题 | 通过标准 | 失败就砍 |
|---|---|---|---|
| G0 | rubric 解析忠实？ | 32/94/100；单任务通道确认部分分 | 解析器 |
| G1 | 验证器准？ | precision≥0.9、recall≥0.8、FA≤5% | 该验证器 |
| G2 | 仿真原子重试涨？ | 3 任务 +10pp | 重试层 |
| G3 | 真机单任务涨？ | 10 任务 ≥6 个 ≥+1/5 | 继续烧全量 |
| G4 | 步骤分抢救有用？ | 失败任务 +10 分 | 抢救模式 |
| G5 | 干扰脚本有用？ | 干扰 trial +20pp | 脚本库 |
| G6 | 全量涨？ | +5pp（约 2 SE） | 回滚 |
| G7 | 合规/延迟？ | 无第二学习模型；p99≤150ms；N 端口隔离 | 架构 |
| G8 | 泛化回归？ | 位置/背景/干扰物/未见物体不显著降 | 相关模块 |
| G9 | 提交工程？ | N 连续端口、token、reset 隔离、180s | 提交 |

### 8.7 统计

- 320 trials，p=0.25：SE=2.42pp；95% CI ±4.7pp。
- 单任务 10 trials：SE=13.7pp；不能单独证明 +5pp。
- 用 paired seeds/固定初始态（若支持）；否则多任务聚合。
- 报告：成功率、步骤分、每泛化类型、失败模式分布、干预次数/收益。

## 10. 风险与合规

### 10.1 单模型合规

| 模式 | 内容 | 合规 | 用途 |
|---|---|---|---|
| **C1** | 一个 VLA + 确定性几何/规则/DP；无第二学习模型 | 最稳 | 默认 |
| **C2** | 一个 VLA + 同 checkpoint VLM head 做语义验证 | 稳（同一模型） | 推荐 |
| **C3** | 一个 VLA + 外部预训练检测器/SAM | 有争议 | 不做，除非官方书面确认 |

RUBRIC 默认 **C1 + C2**：几何谓词是控制器；VLM yes/no 是同一 checkpoint 的另一种提问；演示检索是非参数方法；预算 DP 是确定性算法。

> 若官方 WLA 服务只暴露 action head、无法调用同 checkpoint 的 VLM 前向，则 C2 降级为 C1；不要为了验证去加载第二个 VLM。

### 10.2 风险表

| 风险 | 概率/影响 | 缓解 |
|---|---|---|
| 验证器误报 | 中/高 | 三值 + 二次证据 + 高阈值 + 代价敏感 |
| 验证器漏报 | 中/高 | commit 前 lift/轻推 + VLM |
| evaluator 子失败即终止 | 未知/高 | G0 单任务通道先测；只对非终止失败重试 |
| 重试相关性高 | 中/高 | 估 ρ；按 ρ=0.6 保守规划 |
| 不可逆步骤 | 低/高 | 5/94；先验证；失败 ABORT_SAFE |
| 人为干扰安全 | 中/高 | 暂停/后退/等待；不与人抢 |
| VLM 延迟 | 中/中 | step 边界调用；缓存；C1 兜底 |
| 数据标注不足 | 中/中 | 先做 61 个 PICK/PLACE 步；其余 VLM 兜底 |
| 多物体计数 | 中/中 | 目标检测/计数；VLM 复核 |
| 可变形/透明 | 中/高 | VLM 语义 + 多视角；降低自动化，保留人工规则 |
| 单模型规则解释 | 低/高 | C1/C2；提交前问官方 |
| 端口/并发 | 中/高 | 每端口独立进程；GPU 限流；reset 隔离 |
| 榜单预览误导 | 高/低 | 只当预览；用单任务通道 |

### 10.3 回滚条件

- 如果 G1 验证器不达标：砍掉该技能，退回纯 VLA + 官方脚本。
- 如果 G3 单任务无涨点：砍掉事务重试，只保留步骤分抢救/干扰脚本。
- 如果 G5 干扰脚本无涨点：砍掉脚本，保留通用恢复。
- 如果 G6 全量下降：回滚到第 12 轮 CHUNK-SERVO 基线。
- 如果合规有疑问：退到 C1，去掉 VLM 验证。
