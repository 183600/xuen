# 第 63 轮（承接第 62 轮「ROSE」IP-183~192；灵感循环 II 第 2 轮；本轮灵感：「多模态交互」×「需求洞察」）

> 第 62 轮把 ESEC 的静态闭环升级为 ROSE 的动态闭环：OLP 给对齐以遗憾界、WCV/RSC 给偏差以鲁棒球、SBR/SHC 给经验以课程、Shield 给对话以机制安全。但 ROSE 的全部保证都压在一个**从未被审视的前提**上：损失 ℓ、任务进展 progress、约束集 C_exec、簇遗憾参照 ℓ_ref 被当作「给定的真理」。于是出现一个悖论式风险——**即使 OLP 的遗憾趋于 0，系统也可能以最优的方式做错事**：它收敛到的是「被写进代码的需求」，而不是「人真正想要的需求」。
> 第 62 轮遗留了四个「需求侧」短板：
> 1. **需求是隐变量却被当作常量**：C_exec / u_s / 优先级 w 从对话一次性解析后冻结；人说的「轻一点」「别碰那里」只是需求的稀疏投影，真正的力度上限、可接受路径、时间容忍藏在手势、注视、犹豫与纠正力里。
> 2. **单模态语言通道的信息天花板**：DMS 只吃语言，遇到指代歧义（「那个」）、量级歧义（「轻一点」是 5N 还是 15N）、优先级冲突（快 vs 稳）时只能猜或反复问，且没有「问哪个问题最值」的原则。
> 3. **不确定性没有进入安全层**：Shield 假设 C_exec 正确；若漏解析了「不许越过某区域」，投影算子会把一个错误约束集投影得完美无缺——**机制安全，但语义不安全**。
> 4. **需求会漂移，且会被系统提问塑造**：用户会改主意、会疲劳、会在看到机器人行为后才形成偏好（constructed preference）。第 62 轮的漂移只处理物理环境，不处理「人」这个非平稳源；更危险的是，主动询问本身会引导用户，产生「系统问什么、用户就以为要什么」的操纵性伪需求。

## 0. 直觉与动机

**灵感 1（多模态交互 → MSG：需求槽的多模态接地）**
直觉：语言擅长给「范畴」（要稳），注视给「指代」（那个杯子），手势给「空间约束」（绕过这一侧），纠正力/接触给「量级」（原来 15N 太大力）。四种模态**互补而非冗余**。MSG 把每种模态映射到同一个「需求槽空间」（硬约束槽、软效用槽、优先级槽、时序槽），用可靠性加权的证据融合（而非朴素拼接）得到需求的均值-精度表征。关键洞见：多模态不是「更多输入」，而是**用不同物理量纲去约束同一个隐变量**，从而把不可辨识的需求变成可辨识。

**灵感 2（需求洞察 → RBF + AIR：后验信念 + 主动澄清）**
直觉：需求洞察不是「解析一句话」，而是**贝叶斯实验设计**：维护需求后验 b_t(z)，每次交互都是一次观测；主动选择下一个问题/演示/探测动作，使**期望信息增益（VOI）最大**。这把「多问」变成「问得值」：只有当一次询问带来的后验熵下降足以抵消打扰成本时才问，并在硬约束置信度足够时停止。ROSE 的遗憾是「给定目标后的优化代价」，PRISM 补上「目标本身的辨识代价」。

**灵感 3（需求不确定性 → HCS + ABD：保守接地 + 后验鲁棒行为）**
直觉：安全不能建立在「解析正确」的假设上。HCS 把需求拆成硬约束/软效用/优先级，并对每条硬约束维护「它是否真实存在」的置信度 γ_j；**凡 γ_j 超过低阈值 α_req 的约束都先保守执行**（宁紧勿松），若因此可行域为空，则用 VOI 最高的那条约束去澄清，而不是悄悄放开。ABD 在需求后验上做风险敏感决策：max E_b[u] − λ·CVaR_β[−u]，与第 62 轮物理 φ 球叠加成**双重不确定鲁棒**（物理未知 × 需求未知）。

**灵感 4（需求的 Goodhart 风险 → GSM：规格博弈监控）**
直觉：一旦系统开始「优化推断出的需求」，它就可能钻规格的空子（specification gaming）：把用户往容易满足的方向引导，或利用代理指标与真实偏好的缝隙。GSM 用两个可检验信号守住：① **反事实不变性**——改变与需求无关的干扰（光照、语气）时推断不应变；② **说-做背离**——语言声明偏好 p_s 与纠正行为揭示偏好 p_r 的 KL 散度超阈值即报警并回退重澄清。

**灵感 5（需求漂移 → RDD：把人当非平稳源）**
直觉：用户会改主意，且偏好可能在看到行为后才形成。RDD 对需求后验的「新息」做 CUSUM 变点检测；检测到漂移就**膨胀后验协方差**并触发一轮 AIR，而不是用 EWC 把旧需求焊死。这与第 62 轮 MEL-OA 的「防遗忘」方向相反——**需求层要允许遗忘，物理层才要防止遗忘**。

**灵感 6（合流 → PRISM：需求洞察棱镜闭环）**
MSG（怎么看见需求）→ RBF（需求现在信多少）→ AIR（下一个问题问什么）→ HCS/ABD（不确定时怎么安全地做）→ GSM（有没有在自欺）→ RDD（需求变了吗）→ LEG（把推断讲清楚并征得同意）→ RGL（把需求信念注入 ROSE 的学习与鲁棒层）。PRISM 不推翻 ROSE，而是**在 ROSE 之上加一层「目标从哪来」的元层**：ROSE 让系统「越做越对」，PRISM 让系统「先确认什么是对」。

## 1. 形式化定义（增量：定义 185–194）

- **定义 185（需求洞察棱镜闭环 PRISM）**：PRISM = (ROSE, MSG, RBF, AIR, HCS, ABD, RDD, LEG, GSM, RGL, J_req)。定位：ROSE 之上的「需求元层」；ROSE 仍负责「给定需求后如何越做越好」，PRISM 负责「需求是什么、有多确定、该问什么、何时算够」。
- **定义 186（多模态需求接地 MSG）**：需求对象 θ = (𝒞_h, u_s, w, τ) 嵌入为 z = E(θ) ∈ 𝒵 ⊂ ℝ^k；M 个模态经证据融合 G: (o_1,…,o_M) → b = 𝒩(μ, Σ)，语言给范畴先验、注视给指代、手势给空间约束、纠正力给量级，模态可靠性 α_m 经标定。
- **定义 187（需求信念场 RBF）**：b_t(z) = P(z | ℳ_{1:t})，高斯参数化 b_t = 𝒩(μ_t, Σ_t)，观测模型 o_{m,t} = J_m z + ε_m，ε_m ~ 𝒩(0, R_m/α_m)；是「需求现在信多少」的唯一状态。
- **定义 188（主动信息询问 AIR）**：查询空间 𝒬 = {ask, demo, probe}；q* = argmax_{q∈𝒬} [VOI(q) − λ_c·c(q)]，VOI(q) = I(z; o_q | ℳ_t) = H(b_t) − E_{o_q}[H(b_{t+1})]；停止条件 = 全硬约束已决 ∨ max VOI < c ∨ 熵 < ε_H ∨ 预算耗尽。
- **定义 189（硬约束分离 HCS）**：需求分解为 (𝒞_h, u_s, w, τ)；每条硬约束 j 有存在置信度 γ_j = P[j ∈ 𝒞_h* | b_t]；保守执行集 𝒞_exec^cons = {j : γ_j ≥ α_req}，缺省 α_req=0.05（宁紧勿松）；可行域为空时触发「最可澄清约束」询问而非静默放松。
- **定义 190（歧义鲁棒行为 ABD）**：a* = argmax_{a∈𝒜_safe} {E_{z~b_t}[u_s(a;z)] − λ_β·CVaR_β^{(z)}[−u_s(a;z)]}，𝒜_safe = 同时满足物理球 B(φ̂,r) 与需求执行集 𝒞_exec^cons 的动作；与 WCV 合成「物理 × 需求」双重不确定鲁棒损失。
- **定义 191（需求漂移检测 RDD）**：新息 ν_t = ‖μ_t − μ_{t−1}‖_{Σ^{-1}}；CUSUM 统计量 S_t = max(0, S_{t−1} + ν_t − ν_0)，S_t > h_d 判漂移；处置 = 协方差膨胀 Σ_t ← Σ_t + σ_d²I 并触发 AIR 重澄清；历史保留供审计。
- **定义 192（可读澄清与同意 LEG）**：系统用多模态摘要 Explain(b_t) 表达「我推断你要 X，置信 γ，依据是注视/手势/语言」，请求确认；用户确认/否决/编辑作为最高可靠性观测回灌 RBF；consent_hash 进入证书。
- **定义 193（需求证书 J_req）**：J_req = (J_rose, b_t 摘要, γ 向量, AIR 日志, drift_flag, gaming_score, consent_hash, req_version)；Valid ⇔ Valid(J_rose) ∧ 所有被执行硬约束 γ_j ≥ α_req ∧ ¬drift_flag ∧ gaming_score ≤ δ_G ∧ consent_hash 存在。
- **定义 194（PRISM 闭环算子）**：语义流承载 [MSG 接地 → RBF 更新 → RDD 检测 → GSM 审计 → AIR 选问 → LEG 澄清 → HCS 定执行集 → RGL 注入 ROSE]；实时流仍只读锚点、做 OLP 前向 + WCV 编译 + ABD 动作选择，**需求后验的写操作永不进入实时路径**。

## 2. 关键算法骨架（完整伪代码见产物区）

```python
# MSG + RBF：多模态证据 → 需求后验（信息型融合，非拼接）
mu, Sigma = msd_fuse(o_vis, o_gaze, o_gesture, o_lang, o_force, alpha)
# AIR：问最值的问题；不确定就澄清，问够了就停
q = argmax_q( I(z; o_q | b) - lambda_c * cost(q) )
# HCS/ABD：需求不确定时保守接地 + 后验风险敏感动作
C_exec = {j: gamma_j >= alpha_req};  a = argmax_a E_b[u] - lambda_beta * CVaR_beta[-u]
# RDD/GSM/LEG：漂移、规格博弈、可读澄清
S_t = max(0, S_{t-1} + nu_t - nu_0);  alarm = S_t > h_d or KL(p_stated||p_revealed) > delta_G
```

## 3. 保证概要与推导要点（完整推导见产物区）

- **引理 1（需求误差—效用差分解）**：u_s 对 z 满足 L_u-Lipschitz，则真实效用差 |u(z*) − u(μ_t)| ≤ L_u·‖z*−μ_t‖，取期望 ≤ L_u·√(tr Σ_t)。因此 ROSE 的总次优性 = **需求辨识误差项 L_u√(tr Σ_t) + 优化遗憾项 R_T + 漂移项**；若第一项不下降，第 62 轮的遗憾界在真实效用上毫无意义——这是本轮最核心的论证。
- **引理 2（主动询问的样本复杂度）**：若每次有效查询的期望信息增益 ≥ Δ，则 H(b_T) ≤ H(b_0) − TΔ，达到 ε-辨识所需查询数 T ≥ (H(b_0) − log(1/ε))/Δ；贪心 VOI 在自适应子模条件下有 (1−1/e) 近似。
- **引理 3（需求层安全）**：若 γ_j 标定良好（P[j 真 | γ_j] ≥ γ_j），则「γ_j ≥ α_req 才执行、否则询问/回退」漏掉真实硬约束的概率 ≤ α_req；机制上把第 62 轮 Shield 的「给定 C_exec 安全」升级为「C_exec 本身可能错时仍安全」。
- **引理 4（双重鲁棒）**：ABD 的 (φ, z) 联合风险界 ≤ 物理 WCV 尾部项 + λ_β·需求后验尾部项（三角不等式 + 两个 CVaR 的次可加性）；两源不确定不会互相掩盖，只会叠加保守。
- **定理 1（PRISM-Complete）**：在 A77–A84 下，需求辨识误差收敛、主动询问终止、需求层安全概率 ≥ 1−α_req、漂移可检测、Goodhart 代理背离可报警，且实时路径零需求写操作（ROSE ≤1ms 契约不变）。

## 5. 本轮最大风险

**一句话**：若人的需求本身不可辨识或自相矛盾（偏好随提问被建构），RBF 后验会收敛到一个由系统提问塑造的伪需求，AIR 的「洞察」退化为「引导/操纵」——这是本轮信息论保证、需求层安全论证与 Goodhart 监控共同依赖的**「需求可辨识性」单点假设**（A79/A82）。

| `D_SR = D_KL(p_stated ‖ p_revealed)` | 「说」与「做」的偏好背离 |
| `gaming_score = ω_CF·R_CF + ω_SR·D_SR` | GSM 规格博弈风险分 |
| `Explain(b_t) = (需求摘要, γ 向量, 依据模态, 置信区间)` | LEG 多模态回述 |
| `J_req = (J_rose, b_t, γ, AIR_log, drift_flag, gaming_score, consent_hash, req_version)` | 需求证书 |
| `Δ_util ≤ L_u·√(tr Σ_t) + R_T + drift_term` | 真实效用差分解（本轮核心不等式） |

## 2. 形式化定义（完整版）

**定义 185（需求洞察棱镜闭环 PRISM）** PRISM 是 ROSE 之上的需求元层：ROSE = (USR, MEL, DMS, SRT-Dual, SBR, OLP, WCV, RSC, ARA, Shield, OCB, J_rose) 继续承担「给定目标后的语义-执行-鲁棒闭环」；PRISM 在其上挂载 (MSG, RBF, AIR, HCS, ABD, RDD, LEG, GSM, RGL) 与证书 J_req。不变式：**ROSE 的损失 ℓ 与约束 C_exec 不再被视作常量，而是需求后验 b_t 的函数**；需求后验的全部更新只发生在语义流。

**定义 186（多模态需求接地 MSG）** 需求对象 θ=(𝒞_h,u_s,w,τ) 经嵌入 E 得到 z∈𝒵。M 个模态各自输出需求空间观测：语言 o_lang 给范畴先验（「稳」→低加速度、高刚度约束），注视 o_gaze 给指代（目标物体/禁入区域），手势 o_gesture 给空间半空间约束，纠正力/接触 o_force 给量级（力度上限、速度偏好）。接地算子 G 采用**精度加权贝叶斯融合**：
Λ = Λ_prior + Σ_m α_m J_mᵀ R_m^{-1} J_m，μ = Σ(Λ_prior μ_prior + Σ_m α_m J_mᵀ R_m^{-1} o_m)。
关键：α_m 不是常数，而由「模态自身一致性」与「需求下游可执行性」在线标定（见 A78）；融合**不做朴素拼接**，避免高维冗余模态淹没稀疏但决定性的语言范畴。

**定义 187（需求信念场 RBF）** b_t(z)=P(z|ℳ_{1:t}) 取高斯 b_t=𝒩(μ_t,Σ_t)。每次观测按定义 186 更新；后验可分解为「硬约束存在性」离散部分与「软效用量级」连续部分：b_t = b_t^{exist} ⊗ b_t^{mag}。前者用于 γ_j，后者用于 ABD 的 CVaR。RBF 是需求层唯一可写状态，按版本号与 checksum 提交（沿用 ARA 的 CAS 机制），实时流只读最近快照。

**定义 188（主动信息询问 AIR）** 查询空间 𝒬 = {ask（自然语言澄清）, demo（请求演示一次偏好权衡）, probe（受控探测动作，用物理接触揭示约束）}。选择规则：
q* = argmax_{q∈𝒬, risk(q)≤ρ} [VOI(q) − λ_c·c(q)]，
其中 VOI(q)=I(z;o_q|ℳ_t)=H(b_t)−E_{o_q}[H(b_{t+1})]。对高斯情形 VOI(q)=½log det(I+Σ_t J_qᵀ R_q^{-1} J_q)。停止条件（任一满足）：① 所有硬约束已决（γ_j≥1−α_req 或 γ_j<α_req）；② max_q VOI(q) < λ_c·c(q)；③ H(b_t) < ε_H；④ 预算 B 耗尽（耗尽时进入保守基线并显式报告不确定性）。

**定义 189（硬约束分离 HCS）** 由 b_t^{exist} 计算 γ_j。保守执行集 𝒞_exec^cons={j:γ_j≥α_req}，α_req=0.05。安全集 𝒦_z(𝒞_exec^cons)={a: g_j(a)≤0, ∀j∈𝒞_exec^cons}。若 𝒦_φ∩𝒦_z=∅（过度保守导致不可行），**不得静默放松**，而是：① 选取 𝒞_exec^cons 中 γ 最低、VOI 最高的约束发起 AIR；② 澄清前以最小风险动作（停/退）兜底；③ 若预算耗尽仍冲突，报告「需求冲突」而非执行任一解。

**定义 190（歧义鲁棒行为 ABD）** 在 𝒜_safe 上：
a* = argmax_a { E_{z~b_t^{mag}}[u_s(a;z)] − λ_β·CVaR_β^{(z)}[−u_s(a;z)] }。
CVaR 取需求后验的 β 尾部（β=0.1），即「若我对你的偏好判断错了最坏 10%，代价多大」。与 IP-197 的物理 WCV 合成联合鲁棒损失：
ℓ̃_dual(a) = sup_{φ∈B(φ̂,r)} CVaR_ε^{(φ)}[ E_{z~b_t}[ℓ(a;φ,z)] − λ_β CVaR_β^{(z)}[−u_s(a;z)] ]。
物理不确定与需求不确定分别取 sup 与 CVaR，二者通过次可加性叠加而非相互抵消。

**定义 191（需求漂移检测 RDD）** 语义流每步计算新息 ν_t=‖μ_t−μ_{t−1}‖_{Σ_t^{-1}}；CUSUM：S_t=max(0,S_{t−1}+ν_t−ν_0)，S_t>h_d 判漂移。处置：Σ_t←Σ_t+σ_d²I（膨胀后验，允许重新学习），drift_flag=True，触发 AIR 重澄清，并在 J_req 记录。与 MEL-OA 的方向相反：**需求层允许遗忘，物理层防止遗忘**；两层的 EWC/膨胀互不串扰。

**定义 192（可读澄清与同意 LEG）** 系统生成 Explain(b_t)=（自然语言需求摘要, γ 向量, 依据模态及权重, 置信区间），以多模态形式呈现（语言 + 高亮注视目标 + 手势示意约束边界）。用户响应 r∈{确认, 否决, 编辑} 作为 α=1 的最高可靠性观测回灌 RBF；consent_hash=hash(Explain, r, req_version) 写入 J_req。LEG 同时是**反操纵闸门**：若用户连续确认但 GSM 的 D_SR 升高，系统必须主动提示「你的语言与纠正行为不一致，请复核」。

**定义 193（需求证书 J_req）** J_req=(J_rose, b_t 摘要, γ, AIR_log, drift_flag, gaming_score, consent_hash, req_version)。
Valid(J_req) ⇔ Valid(J_rose) ∧ (∀j∈𝒞_exec^cons: γ_j≥α_req) ∧ ¬drift_flag ∧ gaming_score≤δ_G ∧ consent_hash 存在 ∧ req_version 单调。
审计语义：任何一次执行都可回溯到「当时需求后验的哪个版本、依据哪些模态、问过哪些问题、用户是否同意」。

**定义 194（PRISM 闭环算子）** 语义流执行 [MSG 接地 → RBF 更新 → RDD 检测 → GSM 审计 → AIR 选问 → LEG 澄清/同意 → HCS 定执行集 → RGL 注入 ROSE]。实时流仅执行 [读需求快照 b_t → 读 ARA 锚点 → OLP 前向 + Shrink → WCV 物理编译 → ABD 在 𝒜_safe 选动作 → 派发 → J_req 局部字段]。**需求后验的任何写操作、VOI 计算、询问都不进入实时路径**（A84）。

### IP-193 MSG（多模态需求接地）

```python
def msg_ground(o_lang, o_gaze, o_gesture, o_force, alpha, prior):
    """把四种模态映射到统一需求槽空间，精度加权融合。"""
    mu, Lam = prior.mu.copy(), prior.Lam.copy()
    for o, J, R, a in [(o_lang, J_LANG, R_LANG, alpha['lang']),
                       (o_gaze, J_GAZE, R_GAZE, alpha['gaze']),
                       (o_gesture, J_GEST, R_GEST, alpha['gesture']),
                       (o_force, J_FORCE, R_FORCE, alpha['force'])]:
        if o is None or a < ALPHA_MIN:                  # 缺失/不可信模态直接跳过
            continue
        Lam += a * J.T @ np.linalg.inv(R) @ J           # 精度累加
        mu += a * J.T @ np.linalg.inv(R) @ o
    Sigma = np.linalg.inv(Lam)
    mu = Sigma @ mu
    return Gaussian(mu=mu, Sigma=Sigma, Lam=Lam)

def split_requirement(b):
    """后验分解：硬约束存在性（离散）× 软效用量级（连续）。"""
    return ExistBelief(b, idx=CONSTRAINT_IDX), MagBelief(b, idx=UTILITY_IDX)
```

### IP-194 RBF（需求信念场）

```python
class RequirementBeliefField:
    def __init__(self, k=12, version=0):
        self.b = Gaussian(mu=np.zeros(k), Sigma=np.eye(k))  # 弱先验
        self.version = version

    def update(self, obs_list):
        for o, J, R, a in obs_list:
            if a < ALPHA_MIN: continue
            S = J @ self.b.Sigma @ J.T + R / a
            K = self.b.Sigma @ J.T @ np.linalg.inv(S)       # Kalman 增益
            self.b.mu = self.b.mu + K @ (o - J @ self.b.mu)
            self.b.Sigma = (np.eye_like(self.b.Sigma) - K @ J) @ self.b.Sigma
        self.b.Sigma = 0.5 * (self.b.Sigma + self.b.Sigma.T)  # 对称化
        self.version += 1
        return self.snapshot()                                # CAS 提交快照

    def inflate(self, sigma_d):                               # RDD 触发
        self.b.Sigma += sigma_d ** 2 * np.eye_like(self.b.Sigma)
        self.version += 1
```

### IP-195 AIR（主动信息询问）

```python
def air_choose(b, query_set, lambda_c, rho):
    best, best_score = None, -np.inf
    for q in query_set:
        if q.risk > rho:                                      # 不安全的询问不选
            continue
        Jq, Rq = q.observation_model()
        # 高斯互信息：VOI = 0.5 log det(I + Sigma J^T R^{-1} J)
        voI = 0.5 * np.linalg.slogdet(
            np.eye_like(b.Sigma) + b.Sigma @ Jq.T @ np.linalg.inv(Rq) @ Jq)[1]
        score = voI - lambda_c * q.cost
        if score > best_score:
            best, best_score = q, score
    return best, best_score

def air_should_stop(b, gamma, best_score, lambda_c, eps_H, budget):
    if budget <= 0: return True
    if np.linalg.slogdet(2*np.pi*np.e*b.Sigma)[1] / 2 < eps_H: return True
    if all(g >= 1 - ALPHA_REQ or g < ALPHA_REQ for g in gamma): return True
    if best_score < lambda_c * MIN_COST: return True
    return False
```

```python
def abd_select(A_candidates, b_mag, u_soft, lam_beta=0.5, beta=0.1, n_mc=32):
```

### IP-198 RDD（需求漂移检测）

```python
class RequirementDriftDetector:
    def __init__(self, nu0=1.0, h_d=8.0, sigma_d=0.3):
        self.S, self.nu0, self.h_d, self.sigma_d = 0.0, nu0, h_d, sigma_d

    def step(self, mu_prev, Sigma_prev, mu_now):
        nu = np.sqrt((mu_now - mu_prev) @ np.linalg.pinv(Sigma_prev)
                     @ (mu_now - mu_prev))             # 马氏新息
        self.S = max(0.0, self.S + nu - self.nu0)
        drift = self.S > self.h_d
        if drift:
            self.S = 0.0
        return drift, nu
```

### IP-201 GSM（规格博弈监控）

```python
class GoodhartSpecificationMonitor:
    def __init__(self, delta_G=0.5, w_cf=0.5, w_sr=0.5):
        self.delta_G, self.w_cf, self.w_sr = delta_G, w_cf, w_sr

    def audit(self, G, o, nuisance_do, p_stated, p_revealed):
        # ① 反事实不变性：扰动无关变量 n，需求推断不应变
        r_cf = np.mean([np.linalg.norm(G(o) - G(do(o, n))) for n in nuisance_do])
        # ② 说-做背离：声明偏好 vs 纠正行为揭示偏好
        d_sr = kl_divergence(p_stated, p_revealed)
        score = self.w_cf * r_cf + self.w_sr * d_sr
        return score, score > self.delta_G
```

## 4. 推导

**引理 1（需求误差—真实效用差分解）** 设软效用 u_s(a;z) 对 z 满足 L_u-Lipschitz，行为 a 由后验均值 μ_t 驱动。则对任意真实需求 z*：
u_s(a;z*) − u_s(a*;z*) ≤ [u_s(a;z*) − u_s(a;μ_t)] + [u_s(a;μ_t) − u_s(a*;μ_t)] + [u_s(a*;μ_t) − u_s(a*;z*)]
≤ L_u‖z*−μ_t‖ + (优化遗憾) + L_u‖z*−μ_t‖。
取期望并用 E‖z*−μ_t‖ ≤ √(tr Σ_t)（Jensen）：
**Δ_util ≤ 2L_u·√(tr Σ_t) + R_T + drift_term。**
这正是本轮的核心：第 62 轮的 R_T ≤ D·G̃·√T 只有在 √(tr Σ_t) 足够小时才对*真实*效用有意义；需求辨识误差与优化遗憾是两个独立、相乘于同一目标的误差源。∎

**引理 2（主动询问的熵减少与样本复杂度）** 高斯观测模型下 VOI(q)=½log det(I+Σ J_qᵀR_q^{-1}J_q)≥0，且后验熵 H_t=½log det(2πeΣ_t) 单调不增。若每次被选查询的期望信息增益 ≥Δ，则 H_T ≤ H_0 − TΔ，故达到 H_T ≤ log(1/ε) 需 T ≥ (H_0 − log(1/ε))/Δ。由于互信息对条件独立观测族是自适应子模的，贪心 VOI 的期望信息增益 ≥(1−1/e) 最优，故样本复杂度至多放大 1/(1−1/e)≈1.58 倍。∎

**引理 3（需求层安全的机制保证）** 设 γ_j 标定良好：对真实存在的约束 j，P[γ_j ≥ α_req] ≥ 1−α_req；对不存在的约束，其被误纳入只会导致保守。HCS 仅执行 {γ_j≥α_req} 且对未决约束发起询问/回退，故
P[真实硬约束被漏执行] ≤ Σ_{j∈𝒞_h*} P[γ_j<α_req] ≤ |𝒞_h*|·α_req。
按并集界取 α_req=α_safe/|𝒞_h*| 即得 ≤α_safe。这把 Shield 的「给定 C_exec 的机制安全」升级为「C_exec 可能错时仍以高概率安全」。∎

**引理 4（双重不确定鲁棒的可加界）** ABD 的联合损失 ℓ̃_dual = sup_{φ} CVaR_ε^{(φ)}[E_z[ℓ] − λ_β CVaR_β^{(z)}[−u]]。由 CVaR 的次可加性与 sup 的次可加性：
ℓ̃_dual ≤ sup_φ CVaR_ε^{(φ)}[E_z ℓ] + λ_β sup_φ CVaR_ε^{(φ)}[CVaR_β^{(z)}[−u]]
≤ (物理 WCV 项) + λ_β·(需求后验尾部项)。
两源不确定性只会叠加保守，不会互相掩盖；当需求后验收敛（Σ_t→0）时退化为第 62 轮纯物理 WCV。∎

**定理 1（PRISM-Complete）** 设 A61–A76（第 62 轮）及：
- **(A77)** 需求嵌入低维：z=E(θ)∈ℝ^k，k≪d，且 u_s 对 z 为 L_u-Lipschitz。
- **(A78)** 多模态似然标定：α_m 使观测模型 o_m=J_m z+ε_m 的噪声尺度可信（不可信模态被 ALPHA_MIN 剔除，不会过度自信融合）。
- **(A79)** 需求分段平稳：存在漂移点，段内 θ 固定，漂移幅度与频率有限（RDD 可检测）。
- **(A80)** 硬约束可分解：每条约束存在性独立可判，γ_j 标定良好。
- **(A81)** 查询安全：所有 q∈𝒬 的 risk(q)≤ρ 可判定，probe 不进入不安全域。
- **(A82)** 可辨识性：在已观测模态下 z 至多到「干扰等价类」可辨识，反事实不变性可检验。
- **(A83)** 用户可行使否决：LEG 的确认/否决/编辑以最高可靠性回灌，系统不得绕过。
- **(A84)** 需求写操作仅在语义流；实时流只读快照（继承 ROSE 的实时契约）。
则：
1. **目标有效性**：真实效用差 Δ_util ≤ 2L_u√(tr Σ_t) + R_T + drift_term；当 RBF 后验收缩（自校准的询问/观测）时第一项→0，第 62 轮遗憾界才获得真实意义。
2. **询问效率**：AIR 在自适应子模下以 (1−1/e) 近似最大化信息增益，样本复杂度 ≤1.58×最优；停止规则保证有限预算内终止。
3. **需求层安全**：P[真实硬约束被漏执行] ≤ |𝒞_h*|·α_req，且不可行时不静默放松（HCS 机制）。
4. **漂移适应**：RDD 在段内无误报的前提下，检测延迟随漂移幅度衰减（CUSUM 标准界），膨胀后验允许需求重新学习而不与物理层 EWC 冲突。
5. **规格博弈可检测**：若系统开始利用代理—真实偏好缝隙，则 R_CF 或 D_SR 必上升（否则按 A82 二者在干扰等价类内不可区分），越过 δ_G 触发重澄清。
6. **实时性不变**：需求后验写、VOI、LEG 全在语义流；实时路径新增仅「读快照 + ABD 选择」，保持第 62 轮 ≤1ms 契约。

## 7. 已知风险

**一句话**：若人的需求本身不可辨识或自相矛盾（偏好随提问被建构），RBF 后验会收敛到一个由系统提问塑造的伪需求，AIR 的「洞察」退化为「引导/操纵」——这是本轮信息论保证、需求层安全论证与 Goodhart 监控共同依赖的**「需求可辨识性」单点假设**（A79/A82）。

**次级风险与缓解**：
1. **提问诱导（manipulation）**：VOI 最大化的提问可能把用户推向某个答案 → LEG 强制多模态回述 + 反事实提问（同一需求换两种问法）+ GSM 监控说-做背离，超阈值即停问并报告。
2. **过度询问（annoyance / 瘫痪）**：HCS 保守集可能过紧导致频繁澄清 → 设询问预算 B 与「最小可用信念」阈值，预算耗尽时回退保守基线并显式声明不确定性，而非静默执行。
3. **模态可靠性误标定**：α_m 高估会使融合过度自信 → 用下游可执行性与模态间一致性在线校准；不可信模态硬剔除（ALPHA_MIN）。
4. **需求漂移与遗忘冲突**：需求层要膨胀、物理层要 EWC → 两层参数与协方差严格分离，RDD 只动 RBF，MEL-OA 只动物理适配器，联锁防止互相追逐。
5. **反事实不变性不可检验**：真实部署难以枚举干扰 → 用生成式增强（光照/语气/视角）+ 因果图近似，作为审计信号而非绝对保证；GSM 报警优先于自动修正。
6. **证书膨胀**：J_req 叠加 J_rose 后字段过多 → 分层哈希：b_t 摘要、γ、AIR_log 摘要入证，原始日志落审计存储，证书保持 O(1) 大小。
