### 第 8 轮灵感驱动研究记录

**灵感词**：产学研合作、步骤分

**继承关系**：第 7 轮 CADVS-v7（IP-501~IP-504）把系统从「被动响应指令」推进到「主动推导需求」：DIM 推断 ρ_demand、DRC 用 LLM 推理链量化 η_demand、DAC 用面部表情调制探索度，七硬门保持 fail-closed。本轮延续「硬门不增、只收紧」原则，聚焦「**多来源证据 × 分步证书**」：承认一个现实——安全证据从来不是由单一机构、在单一粒度上产出的。于是引入「步骤分分解器」(PCD) 与「产学研三方证据准入」(TPC)，把「整条轨迹全有或全无」改造成「分步证据链 + 瓶颈聚合」，同时用「分步证书账本」(SCL) 保证可审计、可恢复。

**直觉与动机**：

1. **产学研合作 → 从「单一签发者」到「三方分工的证据联邦」**。v7 的 GGC、MCTM、STM、DIM 名义上是一个流水线，但真实世界里它们的证据来源天然异质：**学**擅长形式化证明（门的可靠性、覆盖率定理），**产**擅长车队级现场日志（长尾失效、真实分布），**研**擅长对抗探测与未知场景合成（红队、主动学习）。关键洞见是：**不同来源的证据不能简单平均**——平均会让「一方高分」掩盖「另一方缺证」；应当取**瓶颈（min）**，并且规定每道门必须有哪几方在场（必需来源集），单方无法把门「抬」过去。合作的价值是**覆盖互补**，不是**投票凑数**。

2. **步骤分 → 从「全有或全无」到「分步证书 + 瓶颈聚合」**。一条抓取-搬运轨迹可切成接近、抓取、抬升、运输、放置若干步。v7 只要有一个硬门不过，整条轨迹作废，连「前 4 步都对、只差最后放置」的诊断信息也被丢掉。引入「步骤分」：给每一步一个分步证书 c_k（该步最弱门的归一化裕度），用 **SoftMin** 聚合为 η_step，既保留「最弱步决定成败」的 fail-closed 语义，又给出连续的反馈信号，支持**从最后已认证步恢复执行**。关键洞见是：**步骤分只能进「评分/排序/恢复」，绝不能进「门限」**——否则局部高分就能补偿局部失败，安全证书会被「洗白」。

3. **两者的交叉 → 分步证据必须带来源标签**。分步证书若由三方分别签发，就必须记录「这一步的这道门，是谁提供的证据、证据之间是否相关」。于是 SCL 以只追加账本形式记录 (step, gate, provider, margin, hash)，既支持审计，也支持在恢复执行时校验「前缀证书未被篡改」。

**关键洞见**：v7 回答「如何从需求推导正确行为」；v8 回答「当证据由多方、多粒度产出时，如何在不新增硬门的前提下，既不因平均而洗白、也不因单方而误判」。七硬门 kc_evidence_forged_v5 记号原样复用；本轮新增的只有：
- IP-505 PCD（步骤分分解器，SoftMin 瓶颈聚合），
- IP-506 TPC（产学研三方证据准入，min 瓶颈 + 必需来源集 + 相关性度量），
- IP-507 SCL（分步证书账本，只追加、可审计、支持恢复），
- IP-508 EFA-v8（七硬门不变，证据准入前置，η_step 只作用于评分）

**形式化目标（增量）**：

1. **PCD（Process Credit Decomposer）**：<br>
   - 分段器 Seg: x ⟼ (x_1, …, x_K)，K 为步数<br>
   - 分步证书 c_k = min_g clamp(m_k^g / τ_g, 0, 1)，其中 m_k^g 为第 k 步第 g 门的裕度<br>
   - 步骤分 η_step = SoftMin_β(c_1..c_K) = -(1/β)·ln( (1/K)·Σ_k e^{-β c_k} )<br>
   - 性质：min_k c_k ≤ η_step ≤ min_k c_k + (ln K)/β，β→∞ 时退化为 min<br>
   - 关键步集 C* = argmin_k c_k；恢复前缀 = 第一个 c_k < 1 之前的已认证段

2. **TPC（Tri-party Provenance Consensus）**：<br>
   - 证据源 P = {学 A, 产 I, 研 R}，每道门有必需来源集 P_g^req<br>
   - 门信号 m_g^v8 = min_{p ∈ P_g^req} m_g^p（瓶颈，非平均、非最大）<br>
   - 必需来源缺失 ⇒ m_g^v8 = 0（fail-closed），单方无法单独放行<br>
   - 相关性度量：若 ρ_{pq} > ρ_max，则两源并为一个「有效独立来源」；只用于报告「交叉验证增益」，不改变 min 的安全方向

3. **SCL（Step Certificate Ledger）**：<br>
   - 记录 rec = (traj_id, t, {c_k}, {m_k^g, provider}, root_hash)<br>
   - 只追加；恢复执行前校验前缀 root_hash，防止「用未认证前缀冒充已认证」

4. **EFA-v8（七硬门不变 + 分步证据）**：<br>
   - 门准入改为「逐步 AND」：Pass_v8(x) = ∧_k ∧_g [m_{k,g}^v8 ≥ τ_g]<br>
   - 评分：ECS_v8 = ECS_v7 · η_step，η_step ∈ (0,1]，**只降不升**<br>
   - 硬门阈值 τ_i^v8 = τ_i^v7，**不随 η_step 改变**（与 v7 的阈值漂移风险解耦）

5. **形式化定义**：给定 v7 选出的轨迹 x：<br>
   - (c_1..c_K) = PCD.step_certificate(Seg(x))；η_step = SoftMin_β(c)<br>
   - m_g^v8 = TPC.admit(g, evidence_g(x), corr)，g ∈ 七门<br>
   - 若 ∃k,g: m_{k,g}^v8 < τ_g ⇒ 从最后已认证步恢复或回退 v7 规则提议<br>
   - 否则接受 x，SCL.append(rec)，ECS_v8 = ECS_v7 · η_step

**本轮最大风险**：**步骤分的组合谬误与产学研证据的相关性**：局部每一步都「分步合格」，并不等价于全局行为安全（步与步之间的连续过渡、时序耦合、能量累积都可能越界），而三方证据若来自同一数据源或存在共谋，min 虽不放大危险、却会让「交叉验证」的名义增益蒸发——系统可能在一个「看似被三方、逐步认证」的证书下，执行一条全局从未被真正认证过的轨迹。

## 2. 关键算法骨架

### IP-505 PCD：步骤分分解器

```python
@dataclass
class ProcessCreditDecomposer:
    """PCD：把轨迹切成 K 步，给出分步证书与瓶颈步骤分 η_step。"""
    segmenter: Callable[[Trajectory], list[Step]]
    gate_margins: Callable[[Step], torch.Tensor]   # 七硬门归一化裕度 ∈ [0,1]^7
    tau: torch.Tensor = field(default_factory=lambda: torch.full((7,), 0.7))
    beta: float = 8.0

    def step_certificate(self, step: Step) -> float:
        m = self.gate_margins(step)                # (7,)
        c = torch.clamp(m / self.tau, max=1.0)     # 归一化到 [0,1]
        return float(c.min())                      # 该步最弱门

    def score(self, x: Trajectory) -> tuple[float, list[float], int]:
        steps = self.segmenter(x)
        cs = torch.tensor([self.step_certificate(s) for s in steps])
        # SoftMin_β：min_k c_k ≤ η ≤ min_k c_k + ln(K)/β
        eta = float(-torch.logsumexp(-self.beta * cs, dim=0) / self.beta
                    + math.log(len(cs)) / self.beta)
        k_star = int(torch.argmin(cs))
        return eta, cs.tolist(), k_star

    def resume_prefix(self, x: Trajectory, cs: list[float]) -> tuple[Trajectory, int]:
        """第一个未达标步之前的前缀为「已认证前缀」；k=0 表示无可恢复前缀。"""
        k = next((i for i, c in enumerate(cs) if c < 1.0), len(cs))
        return x.prefix_until(k), k
```

### IP-506 TPC：产学研三方证据准入

```python
@dataclass
class TriPartyProvenanceConsensus:
    """TPC：产学研三方证据的准入算子（瓶颈 min，非平均/最大）。"""
    required: dict[str, set[str]] = field(default_factory=lambda: {
        'grasp':  {'A', 'I'},     # 几何/力学：学术形式化 + 产线现场
        'topo':   {'A', 'I'},     # 空间拓扑：学术形式化 + 现场地图
        'intent': {'A', 'R'},     # 指令意图：学术对齐 + 研究红队
        'demand': {'A', 'R'},     # 需求意图：学术因果 + 研究探测
    })
    rho_max: float = 0.8

    def admit(self, gate: str, evidence: dict[str, float], corr: dict) -> float:
        req = self.required.get(gate, {'A'})
        if not req.issubset(evidence):
            return 0.0                       # 必需来源缺失 → fail-closed
        # 瓶颈：任一方低分都拉低整道门；单方无法「抬」过阈值
        return min(evidence[p] for p in req)

    def effective_support(self, gate: str, corr: dict) -> int:
        """相关性合并后的有效独立来源数，仅用于报告交叉验证增益。"""
        req = self.required.get(gate, {'A'})
        groups = self._correlation_groups(req, corr)
        return len(groups)                   # 相关性高 → κ_g 变小，但 min 安全性不变

    def _correlation_groups(self, providers: set[str], corr: dict) -> list[set[str]]:
        groups = [{p} for p in providers]
        merged = True
        while merged:
            merged = False
            for i in range(len(groups)):
                for j in range(i + 1, len(groups)):
                    if any(corr.get((p, q), 0.0) > self.rho_max
                           for p in groups[i] for q in groups[j]):
                        groups[i] |= groups[j]
                        groups.pop(j)
                        merged = True
                        break
                if merged:
                    break
        return groups
```

### IP-507 SCL：分步证书账本

```python
@dataclass
class StepCertificateLedger:
    """SCL：只追加分步证书账本；恢复前校验前缀哈希。"""
    path: str

    def _root(self, cs: list[float], evidence: dict) -> str:
        payload = repr((cs, sorted(evidence.items()))).encode('utf-8')
        return hashlib.sha256(payload).hexdigest()

    def append(self, traj_id: str, cs: list[float], evidence: dict) -> str:
        root = self._root(cs, evidence)
        rec = {'id': traj_id, 'ts': time.time(), 'steps': cs,
               'evidence': evidence, 'root': root}
        with open(self.path, 'a', encoding='utf-8') as f:
            f.write(json.dumps(rec, ensure_ascii=False) + '\n')
        return root

    def verify_prefix(self, traj_id: str, k: int, cs_prefix: list[float],
                      evidence: dict) -> bool:
        rec = self._last_record(traj_id)
        return rec is not None and rec['steps'][:k] == cs_prefix \
               and rec['root'] == self._root(cs_prefix, evidence)
```

### IP-508 EFA-v8：七硬门不变 + 分步证据

```python
@dataclass
class EvidenceForgingAssemblerV8:
    """EFA-v8：七硬门不变；证据准入前置（TPC）；η_step 只进评分。"""
    v7: EvidenceForgingAssemblerV7
    pcd: ProcessCreditDecomposer
    tpc: TriPartyProvenanceConsensus
    scl: StepCertificateLedger
    gates: tuple[str, ...] = ('grasp', 'topo', 'wrench', 'val',
                              'intent', 'demand', 'novel')
    tau: torch.Tensor = field(default_factory=lambda: torch.full((7,), 0.7))

    def select(self, L: str | None, t_now, context) -> tuple[bool, Trajectory | None, str]:
        # 1) 先让 v7 选出候选（需求建模/推理链/软因子链保持原样）
        ok, x, tag = self.v7.select(L, t_now, context)
        if not ok or x is None:
            return ok, x, tag

        # 2) 分步证书 + 瓶颈步骤分
        eta_step, cs, k_star = self.pcd.score(x)

        # 3) 逐步 AND 的三方证据准入（只收紧，不新增第八道硬门）
        admitted = {}
        for k, step in enumerate(self.pcd.segmenter(x)):
            for g in self.gates:
                ev = self._provider_evidence(g, step, context)   # {A: m, I: m, R: m}
                admitted[(k, g)] = self.tpc.admit(g, ev, context.correlation)

        if not all(admitted[(k, g)] >= self.tau[i]
                   for k in range(len(cs)) for i, g in enumerate(self.gates)):
            return self._resume_or_fallback(x, cs, k_star, t_now, context)

        # 4) 账本 + 评分：η_step 只乘 ECS，不改任何阈值
        self.scl.append(x.id, cs, admitted)
        self._last_eta_step = eta_step
        return True, x, 'FORGED_CGE_V8'

    def _resume_or_fallback(self, x, cs, k_star, t_now, context):
        prefix, k = self.pcd.resume_prefix(x, cs)
        if k == 0:
            return self.v7.select(None, t_now, context)          # 无可用前缀
        if not self.scl.verify_prefix(x.id, k, cs[:k], {}):
            return self.v7.select(None, t_now, context)          # 前缀不可信
        return self.v7.select_resume(prefix, t_now, context)     # 未执行后缀重新过门

    def ecs_v8(self, x, n_flow, s_emo, eta_factors, eta_step: float) -> float:
        """η_step ∈ (0,1]，只能降低评分；τ_i^v8 = τ_i^v7 保持不变。"""
        return self.v7.ecs_v7(x, n_flow, s_emo, eta_factors) * eta_step
```

### 集成流水线（v7 → v8）

```
离线/慢时域：
  学方：七硬门可靠性/覆盖率的定理级证明 → 形式化证据包（可机检）
  产方：车队现场日志 → 各门经验裕度分布 + 长尾失效清单
  研方：红队/未知场景合成 → 对抗证据 + 覆盖缺口报告
  三方证据对齐：统一到 (gate, margin, provider, coverage) 四元组 → 签名入库

在线准入（亚秒级）：
  v7.select(L) ──▶ 候选 x
  PCD.score(x) ──▶ {c_k}, η_step, k*        （复用 v7 门裕度，增量 < 0.05 ms）
  TPC.admit(step, gate) ──▶ min over P_g^req （每步每门 O(3)）
  Pass_v8(x) = ∧_k ∧_g [m ≥ τ]              （逐步 AND）
  若失败：SCL 校验前缀 → 从最后已认证步恢复 / 回退 v7 规则提议
  若通过：SCL.append；ECS_v8 = ECS_v7 · η_step

在线控制环（目标 < 0.85 ms）：
  分步证书与门裕度同源，无需重复物理仿真；TPC 为 O(1) 查表；
  SCL 追加异步落盘，不阻塞控制环。
```

## 4. 正确性论证（增量更新）

### 定理 13（步骤分不洗白）

**陈述**：设 η_step = SoftMin_β(c_1..c_K)，则对任意 β>0 有 min_k c_k ≤ η_step ≤ min_k c_k + (ln K)/β。且 η_step 只乘入 ECS_v8、不进入任何硬门阈值 τ_i^v8。因此：
- 只要存在某步某门未达标（c_k < 1），该失败**不能**被其他步的高分补偿而通过门准入；
- ECS_v8 = ECS_v7 · η_step ≤ ECS_v7，评分排序只会收紧，不会放宽；
- 故 Exec_CADVS-v8 ⊆ Exec_CADVS-v7，步骤分不产生「局部合格 → 全局放行」的洗白通道。

**证明**：SoftMin 的上下界由 log-sum-exp 的单调性直接得到（见 §1 定义）。门准入 Pass_v8 = ∧_k ∧_g [m_{k,g}^v8 ≥ τ_g] 是对所有步、所有门的合取，任一失败即整体失败，与 η_step 取值无关。η_step ≤ 1，乘到 ECS 上只降不升；τ 保持不变，故不存在阈值下降导致的执行集扩张。合取 + 只降评分 ⇒ 子集关系成立。∎

### 定理 14（三方证据准入的单调性）

**陈述**：设 v7 的证据融合算子 F ∈ {mean, max}，v8 的门信号 m_g^v8 = min_{p∈P_g^req} m_g^p，则 m_g^v8 ≤ m_g^v7。因此：
- Exec_CADVS-v8 ⊆ Exec_CADVS-v7；
- 任一必需来源缺失 ⇒ m_g^v8 = 0 ⇒ 该门 fail-closed，单方无法放行；
- 增加（可选）来源只会使 min 不增，即只会进一步收紧。

**证明**：min ≤ mean ≤ max，故 min ≤ F。必要性由 admit 的提前返回 0.0 保证。增加一个来源只是把 min 的取域扩大，min 单调不增。相关性合并只改变有效独立来源计数 κ_g，不改变 min 的取值方向，故不影响安全性，只影响「交叉验证增益」的声明强度。∎

### 定理 15（恢复执行的安全性）

**陈述**：从已认证前缀恢复执行，不会比从零执行更宽松：
- 已认证前缀满足 Pass_v8；未执行后缀在恢复时仍需逐步重新过门；
- SCL 的 root_hash 校验保证前缀证书未被篡改；
- 故恢复路径的准入集 ⊆ 从零执行的准入集。

**证明**：恢复只跳过已认证前缀的重复计算，不跳过其后缀的门判定；前缀的 root_hash 与账本一致才能恢复，排除「用未认证前缀冒充已认证」。后缀判定与从零执行使用同一 Pass_v8，故其准入集不会更大。∎

### 诚实声明

- **步骤边界是假设**：Seg 若切在错误位置，可能把一次连续越界切成两个「各自合格」的步；分步证书无法捕获步间过渡（速度、能量、时序耦合）的越界。
- **SoftMin 的松弛**：有限 β 给出 (ln K)/β 的松弛；β 太小会让最弱步被「平均化」，β 太大会放大数值误差。需按 K 标定 β ≥ ln K / ε。
- **min 的代价是可用性**：任一必需来源偏低就整门失败，可能造成大量误拒；必需来源集的选择本身是安全/可用性的权衡。
- **相关性只降增益、不降安全**：ρ_{pq} 高时 min 仍安全，但「产学研交叉验证」的覆盖增益名不副实；κ_g 只是报告量，不能反过来当作安全裕度。
- **账本隐私**：provider 标签与证据指纹可能泄露供应链信息；需最小化记录并做访问控制。

## 5. 实验设计与验证计划（仿真 → 实机）

### 5.1 实验设计（MuJoCo 3.x + MJX）

- **平台**：机械臂 UR10e（6DOF）+ 移动底盘（2DOF）+ 语音指令合成器 + 摄像头
- **三方证据构造**：
  - 学方：对七门做形式化区间验证，输出每门的可靠性下界（覆盖率 × 置信度）
  - 产方：50k 条车队现场 episode，统计每门经验裕度分布与长尾失效
  - 研方：红队/未知场景合成 5k 条，输出对抗证据与覆盖缺口
- **对照**：v7-full、v8-full、消融 A21（η_step≡1，无分步）、A22（步骤分改为加权求和，检验洗白）、A23（TPC 退化为单源，检验单方放行）、A24（关闭相关性合并，检验增益虚高）、A25（关闭恢复执行）
- **场景**：
  - (a) 分步放置：中途滑移，前 4 步合格、第 5 步抓取裕度不足 → 验证不洗白 + 从第 4 步恢复
  - (b) 三方证据冲突：学方证明通过、产方现场日志低分 → min 触发拒绝，而非平均放行
  - (c) 相关证据：产方与研方共用同一数据源 → κ_g 下降，报告「增益蒸发」但安全不变
  - (d) 恢复篡改：伪造前缀 root_hash → verify_prefix 拒绝恢复
- **指标**：
  - 安全性：洗白率（部分合格却全局放行的比例）、单方放行率、恢复后越界率
  - 可用性：误拒率、恢复成功率、平均恢复步数
  - 证据质量：κ_g 分布、三方分歧度、门裕度覆盖率
  - 时序：P99 控制环、SCL 落盘延迟

## 7. 本轮最大风险（最终确认）

**一句话**：**步骤分的组合谬误与产学研证据的相关性**：局部每一步都「分步合格」，并不等价于全局行为安全（步与步之间的连续过渡、时序耦合、能量累积都可能越界），而三方证据若来自同一数据源或存在共谋，min 虽不放大危险、却会让「交叉验证」的名义增益蒸发——系统可能在一个「看似被三方、逐步认证」的证书下，执行一条全局从未被真正认证过的轨迹。
