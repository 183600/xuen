## 1. 直觉与动机（两个灵感的碰撞）

### 灵感 1（对话管理 → 一次 episode 就是一场有轮次、有信念、有修复的对话）

**直觉。** 大家把 VLA 当成一个「独白者」：看到一帧，一次性说出一串动作（chunk），然后不管世界有没有听懂。但接口实际是一个**轮次协议**：指令是 system prompt，chunk 是机器人这一轮的发言，新观测是世界的回复，成功/失败是世界有没有按预期回应。真正缺的不是更聪明的单轮生成，而是对话管理里的四件事：**信念状态**（我记得做到哪、哪些已经确认）、**轮次**（现在该我动还是该让人）、**grounding**（我预期的效果发生了吗）、**修复**（没发生就换一种说法；再不行就主动探测；最后让位）。由于 F23 明确没有中途语言通道，这场对话的「对方」只能是物理世界，不能是人；因此所有澄清都必须落成主动感知，而不是提问。

**严谨定义（轮次制操作对话）。** 把 episode 写成轮次化 POMDP：
`M = (S, O, A, G, D, b, π_VLA, π_TDM, CG)`。
信念 `b_t = (g_t, p_t, κ_t, u_t, τ_t)`：当前子目标、进度、接触/抓取/人手事件、轮次所有权、剩余时间。对话动作集
`D = {CONTINUE, ADVANCE, REPAIR, PROBE, YIELD, COMMIT, TERMINATE}`。
grounding 谓词
`G_t = 1[sim(ê_t, e_t) ≥ τ_g]`，其中 `ê_t` 是本轮预期效果（来自子目标计划与前向预测），`e_t` 是新观测里估计的效果。
修复采用对话式升级链 `R_0 ≺ R_1 ≺ R_2 ≺ R_3`：重发 < 重规划 < 主动探测 < 让位/保守态；选满足「期望收益 > 代价」的最低层级。轮次所有权 `u_t ∈ {R,H}`；人手进入执行域就是 **barge-in**，只能 `YIELD/HOLD`；恢复需「人离开 `T_settle` + 重新 grounding + 时间足够」。澄清动作是信息论意义上的「提问」：
`a* = argmax_{a∈A_epi} (E[ΔH(b_t)|a] − λ c(a)) / c(a)`，但 `a` 只能是安全、可逆的探测动作。

**关键反直觉点：VLA 缺的不是智能，而是对话状态；一句指令不是一锤子买卖。** 现有 I4/I5 已经分别做了「中断门控」和「恢复示教」，但它们是散落的 if-else；对话管理把它们统一成「信念 + 轮次 + grounding + 修复」。更关键的是：**一个每轮都调用大模型做状态跟踪的对话管理器会把延迟预算吃光**——这正是第二个灵感的入口。

### 灵感 2（低延迟推理 → chunk 执行期是免费的「思考时间」，也是对话的「对方说话时间」）

**直觉。** 语音对话系统里有一个成熟技巧：用户还没说完，系统就根据半句话**投机式预生成**一个回复；等用户说完再验证/修正。机器人这里几乎是同构的：机器人执行当前 chunk 的时间 `H = T_a·Δt`，就是「用户还在说话」；下一个观测到达，就是「用户说完了」。这段时间 GPU 本来是空的（机器人在动，不在算），可以拿来预生成**下一轮**的 draft。新观测一到，先用对话管理器的 grounding 信号做廉价验证：世界按预期演化 → 接受 draft、立即回复；世界给了意外 → 丢掉 draft、跑全量模型，并让对话管理器进入修复。**一句话：只在世界让你意外时才付全量推理的钱。** 这也是预测编码/主动推断的味道：预测误差才是昂贵更新的触发器。

**严谨定义（投机轮次）。** 设 `H = T_a·Δt`，全量推理延迟 `L_full`，draft 延迟 `L_draft`（在 H 内完成），验证延迟 `L_verify`。第 t 轮发出 chunk 后，用当前观测 `o_t` 与预测的下一子目标 `g_{t+1}` 预生成 `ã_{t+1}`；新观测 `o_{t+1}` 到达后，用 grounding/潜在一致性分数 `s_t` 验证。接受概率 `p = P(s_t ≥ τ)`，错误接受率 `ε_fa`。则每轮响应延迟
`L_resp = L_verify + (1−p)·L_full`，
轮次周期 `P = H + L_resp`，有效轮次率 `f_turn = 1/P`。
无投机时 `P_0 = H + L_full`，故每轮节省 `p·(L_full − L_verify) ≈ p·L_full`。
若 `L_verify + (1−p)L_full ≪ H`，则 `P ≈ H`，达到「延迟被隐藏」的零等待区；若 `p=0`，投机白做，退化为无投机。
关键推论：**`T_a` 不只是控制参数，它是投机窗口。** `H` 越大，越有空间预生成，但反馈越粗；`H` 越小，反馈越细，但 draft 来不及做、且每轮都要付 `L_full`。存在一个由任务开环发散率、容差、`L_full`、`p(H)` 共同决定的最优 `T_a`。

**关键反直觉点：低延迟推理不是 serving 的工程细节，而是对话管理能否成立的前提。** 对话管理想多要几轮修复，就必须把每轮延迟压到 `H` 以下；否则「多一轮」本身就要多付一次全量推理，修复的收益被延迟成本吃掉。

### 两者统一：TURN（Turn-level Unified Runtime）

**直觉。** 对话管理决定「这一轮说什么」（语义层），低延迟推理决定「这一轮多快能说」（时延层），两者共用同一个单位——**action chunk = 对话轮次**。更漂亮的是：**对话管理器的 grounding 信号，恰好就是投机引擎的验证器**。同一个「预期效果 vs 实际效果」的失配，既触发修复，也触发全量重算；不需要再接一套独立的验证模型。这形成正反馈：

> 更好的对话状态 → 更准的下一子目标预测 → 更高的 draft 接受率 `p` → 更低的 `L_resp` → 更多可靠轮次 → 更好的对话状态。

TURN 的三层：

1. **TDM（I10，语义层，1–2Hz）**：缓存式子目标计划 + 轻量 progress/grounding 头 + 规则 FSM；每轮开销 <2ms，不跑第二个大模型。
2. **STE（I11，时延层）**：chunk 执行期预取下一轮 draft；新观测到达后用 grounding/潜在一致性验证；失败则全量重算； deadline 到则 anytime 安全回退。
3. **TSA（I6 v3，调度层）**：N 端口共享 GPU 的 deadline-aware 调度、投机准入控制、p99/方差门禁。

**本轮结论：中期胜负手不是更大的模型，而是「轮次运行时」——把模型延迟藏进机器人执行窗口，把观测变成对话状态，把世界给的意外变成唯一的昂贵计算触发器。**

## 2. 对 v1.1 痛点的增量修订

- **新增 P9（轮次制接口）**：有效反馈率是 `1/(H + L_resp)`，不是 15Hz；I6 原先把延迟当部署指标，本轮升级为**决定对话粒度的一等公民**。
- **新增 P10（无中途语言）**：F23 关闭了「问人」的通道；任何对话管理都必须内部化，澄清只能是主动感知，不能假设有第二轮语言输入。
- **新增 P11（无子目标标注）**：官方数据无 subtask/phase 标签（F25）；TDM 的计划与进度必须从得分点 + 合成示教弱监督而来，误差会沿轮次复合。
- **新增 P12（N 端口共享 GPU）**：投机预取与全量回退争同一张卡；没有准入控制，p99 与方差会恶化，反而违反 F21 的可信度要求。
- P5（时间压力）补充：修复次数与轮次率直接挂钩，180s 预算要按「轮次预算」而非「步数预算」分配。
- P8（示教质量）补充：支线探针显示 43% episode 有 ≥2 次闭合循环（F27），说明「重抓/多轮」其实在示教分布内，TDM 的 REPAIR 不必从零发明。

## 3. 研究问题（本轮立项 Q9–Q12，Q1–Q8 保留）

- **Q9（轮次率与延迟）**：给定任务开环发散率 λ、容差 ε、`L_full`、`p(H)`，最优 `T_a`/`H` 是多少？投机在什么条件下净赚（扣掉 GPU 争用）？零等待区 `L_resp ≪ H` 能否在 N=3–5 端口下稳定达到？
- **Q10（对话状态的最小充分表示）**：`b_t` 的哪些分量真正预测子目标成功/失败？能否只用轻量视觉 + 本体 + 缓存特征，而不引入第二个大模型？grounding 阈值如何标定，才能既不漏修复、又不在标称场景误报？
- **Q11（投机接受的可证伪性）**：如何用离线 replay 标定验证器，使错误接受率 `ε_fa` 有分布无关上界？接受阈值、动作误差、成功率三者的 Pareto 前沿是什么？
- **Q12（修复经济学）**：在剩余轮次/时间预算下，何时 CONTINUE / ADVANCE / REPAIR / PROBE / YIELD？不可逆动作（释放、倾倒、插到位）是否需要更高的 grounding 门槛？

## 4. 设计原则（新增 PR6–PR8，PR1–PR5 保留）

- **PR6 轮次预算律**：`f_turn = 1/(H + L_resp)`，`L_resp = L_verify + (1−p)L_full`。任何推理期组件引入的延迟，都必须用「轮次率提升」或「已验证的成功率增益」来支付；若它使 `L_resp` 超过 `H` 却不提高 `p`，就是净亏损。与 PR4（部署门禁）互补：PR4 管能不能上线，PR6 管轮次是否值。
- **PR7 对话内化律**：没有中途语言通道（F23），所以对话状态必须完全由可观测信号支撑；TDM 只能通过 prompt/条件化影响**同一个** VLA，不能引入第二个任务策略；澄清只能落成安全、可逆的主动感知；不得用「继续执行」假装听懂。
- **PR8 投机可证伪律**：每一次投机接受都必须有廉价、已标定的验证器、错误接受率上界、以及全量模型回退；报告 `p`、`ε_fa`、p99、方差。没有验证的「加速」不能上计分通道。
- PR1–PR5 保留（第 1–2 轮）：计分轴对齐、单模型边界、部署预算、数据杠杆律。

## 6. 本轮最大风险

**一句话**：整个 TURN 都押在「grounding 信号能把『世界因我们的动作而变』与『世界因泛化/人手而变』分开」上——若这个谓词在 5 类泛化轴上不可分，STE 会要么拒绝有效 draft（延迟爆炸），要么接受错误 draft（修复被污染），对话管理与投机加速会同时失效；因此 Q10/Q11 的离线标定必须先于任何真机投入。

# UniBot-V1 参赛创新点清单（第 3 轮 v1.3 · 轮次运行时 TURN）

## 0. 一句话架构

**TURN = TDM（语义层：这一轮说什么）+ STE（时延层：这一轮多快能说）+ TSA（调度层：谁先拿到 GPU）。**

```
                    ┌─────────────────────────────────────────┐
                    │  TDM (I10)  1–2 Hz, <2 ms              │
   instruction ───▶ │  plan library → belief b_t → dialogue  │
   first obs        │  act d_t ∈ {CONTINUE, ADVANCE, REPAIR, │
                    │  PROBE, YIELD, COMMIT, TERMINATE}      │
                    └───────────────┬─────────────────────────┘
                                    │ prompt / subgoal / expected effect ê_t
                                    ▼
   chunk_t-1 ─────▶ ┌─────────────────────────────────────────┐
   executing (H)    │  STE (I11)  prefetch draft ã_{t+1}      │
                    │  verify with grounding G_t / latent err │
                    │  accept p → L_resp ≈ L_verify           │
                    │  reject → full VLA fallback             │
                    └───────────────┬─────────────────────────┘
                                    │ requests / deadlines
                                    ▼
                    ┌─────────────────────────────────────────┐
                    │  TSA (I6 v3)  N ports, EDF, admission  │
                    │  verify > full > draft; p99/variance    │
                    └─────────────────────────────────────────┘
```

**核心恒等式**：`H = T_a·Δt`；`L_resp = L_verify + (1−p)L_full`；`P = H + L_resp`；`f_turn = 1/P`。投机把 `P_0 = H + L_full` 降为 `P`，每轮期望节省 `p(L_full − L_verify)`；`T_a` 是投机窗口，不是纯控制参数。

## 1. 新点 I10：TDM 轮次对话管理器（Turn Dialogue Manager）★★★★★

### 动机
- F23：语言只在 episode 开始时给一次，无中途语言通道。现有 VLA 是「独白式」chunk 生成器：没有显式信念、没有轮次、没有 grounding、失败只会重复动作。
- 长程任务（ArrangePlates、PackBag、OrganizeBookshelf、ToolboxStorage 等）的失败往往不是单步动作错，而是**子目标漂移**：抓错了、放错了、重复抓、提前停。VLA 的观测历史栈能记住画面，但没有一个「我们聊到哪了」的状态。
- 支线已验证的 MDM 概念给出了信念/轮次/grounding/repair 的骨架；本点的增量是**低延迟实现**：计划在 reset 期检索缓存，状态更新用共享/轻量特征 + 小头，每轮 <2ms，绝不每轮调大模型。

### 与现有方案差异
- 层次化 VLA：只有「高层子目标 + 低层动作」，没有轮次、共同 ground、修复层级、澄清经济学。
- 行为树：有结构，但没有不确定性信念，也不会从失败中升级修复策略。
- 纯 POMDP 规划：在 6B VLA 上不可实时。
- 本点：**符号槽 + 轻量头 + 规则 FSM** 的中间路线；计划在 reset 期一次性检索，轮次内只做 O(1) 更新；与 VLA 的唯一耦合是 prompt/条件化，不引入第二个任务策略。

### 形式化定义
- **信念**：`b_t = (g_t, p_t, κ_t, u_t, τ_t)`，其中 `g_t` 是当前子目标索引/状态，`p_t ∈ [0,1]` 是进度，`κ_t ∈ {FREE, CONTACT, GRASP_OK, GRASP_FAIL, HUMAN, NONE}` 是事件，`u_t ∈ {R,H}` 是轮次所有权，`τ_t` 是剩余时间/轮次预算。
- **计划**：`G = (g_1,…,g_K)`，每个子目标带 `(得分权重 w_k, 预期效果 ê_k, 前置条件 pre_k, 修复提示 repair_k)`。计划在 reset 期由「指令嵌入 + 首帧物体 + I9 检索先验 + 官方得分点」从离线计划库检索；无匹配则退回通用模板（approach→grasp→transport→place→verify）。
- **grounding**：`G_t = 1[sim(ê_t, e_t) ≥ τ_g]`；`e_t` 由效果头从新观测估计。连续 `n_g` 次 `¬G_t` 触发升级修复。
- **对话动作**：`D = {CONTINUE, ADVANCE, REPAIR, PROBE, YIELD, COMMIT, TERMINATE}`。
- **修复链**：`R_0 ≺ R_1 ≺ R_2 ≺ R_3`：重发当前子目标 < 按新信念重规划 < 主动探测 < 让位/保守态。选择最低层级 `i` 使 `q_i·V_remaining / c_i ≥ λ`（`q_i` 为成功率，`c_i` 为轮次/时间代价，`V_remaining` 为剩余任务价值）。每 episode 的修复次数与探测次数有硬上限。
- **轮次**：`u_t=H` 时只能 `YIELD/HOLD`；恢复需 `人离开 T_settle ∧ 重新 grounding ∧ τ_t > τ_min`。
- **澄清 = 主动感知**：`a* = argmax_{a∈A_epi} (E[ΔH(b_t)|a] − λ c(a))/c(a)`，`A_epi` 是安全、可逆的探测动作（换视角、轻推、重新接近、轻夹测试）；禁止在人手执行域内探测。
- **终止**：`TERMINATE` 只在计划完成或时间不足时触发；不可逆动作（释放、倾倒、插到位）要求更高的 grounding 门槛 `τ_g^irr > τ_g`。

### 技术可行性
- 高。计划库离线构建；进度/效果/事件头是轻量 MLP/小 Transformer；FSM 是规则；每轮更新 <2ms（CPU/GPU 均可）。
- 标签来源：官方得分点（I5 逆向）+ 合成示教（I5）+ 110 语料孪生任务（I2）+ 夹爪开口（F27）。无 subtask 标签（F25）是最大的数据工程，但不是不可解。
- 共享特征优先：验证新观测时本来就要跑一次视觉编码，TDM 直接复用该特征；若不可用，退回轻量编码器（单模型边界见 §9）。

### 所需资源
- 1×24GB GPU 训头 + 离线标定；计划库 1 人周；FSM/工程 2 人周。

### 落地步骤
1. 定义 32 任务的子目标/预期效果模板（先做 5 个代表任务：PlugCharger、ZipUp、PourOutMedicine、OrganizeBookshelf、StoreCups）。
2. 从官方得分点 wiki + 任务视频逆向每任务 3–6 个子目标；构建计划库。
3. 用 I5 的合成「偏离→修正」段训练效果头与修复策略；用 I2 的孪生任务扩充弱标签。
4. 实现 TDM FSM + 预算 + 轮次所有权；离线 replay 验证状态跟踪。
5. 与 I11 联调：TDM 的 `ê_t/G_t` 作为 STE 验证器；STE 的 draft 作为 TDM 的「下一轮假设」。
6. 单任务通道先测「不伤标称」；再测长程/干扰/未见物品轴。

### 风险
- 子目标/效果标签噪声 → 误修复（缓解：置信门控、连续确认、修复次数上限、低置信退回纯 VLA）。
- 计划库与真实评测指令不匹配（缓解：指令嵌入检索 + 通用模板 + reset 期一次轻量重排）。
- 单模型边界：TDM 若被裁定为第二模型（缓解：优先共享 VLA 编码器 + 辅助头；降级为纯 prompt/FSM，不训练独立头）。

## 2. 新点 I11：STE 投机轮次引擎（Speculative Turn Engine）★★★★★

### 动机
- F20：chunk 执行期 `H = T_a·Δt` 是机器人「在动不在算」的空窗；F21：响应时延与波动会被记录。当前默认做法是「等新观测到了再跑全量模型」，把这段免费时间浪费掉。
- 对话管理想多要轮次（多修复、多 ground），但每轮都付 `L_full` 会把延迟预算吃光。低延迟推理的正解不是只把模型压小，而是**把下一轮的推理藏进这一轮的执行窗口**。
- 跨学科类比：语音对话的「增量/投机式应答生成」——用户还没说完，先根据半句话起草回复，等用户说完再验证/修正。机器人这里「用户」是物理世界。

### 与现有方案差异
- 量化/编译/CUDA Graph/双率：降低 `L_full`，但不改变「新观测到了才开始算」的串行结构。
- 世界模型测试时规划：增加 `L_full`，与 PR6 冲突；本点把世界模型降级为**廉价验证器/潜在前向预测**，不做 rollout 规划。
- 本点：**利用执行窗口预取 + 用 grounding 验证 + 失败才全量**。draft 不执行就不产生安全风险；验证失败只损失延迟，不损失动作正确性（有全量回退）。
- 关键融合：**TDM 的 grounding 信号就是 STE 的验证器**；同一个「预期效果 vs 实际效果」的失配，既触发修复，也触发全量重算。

### 形式化定义
- **预取**：第 t 轮发出 `a_t` 后，在 `H` 内用 `o_t` 与 TDM 预测的 `g_{t+1}` 生成 draft `ã_{t+1}`；`L_draft ≤ H` 且调度器允许时才做。
- **验证**：`o_{t+1}` 到达后计算 `s_t = w_g·G_t + w_l·(1 − ||z_{t+1} − ẑ_{t+1}||)`，其中 `G_t` 是 TDM 的 grounding，`ẑ` 是 I7' 轻量潜在前向模型的预测。`s_t ≥ τ` 且通过安全护盾（关节限位/工作空间/最大步长/夹爪状态）则接受；否则全量重算。
- **标定（选择性风险控制）**：在离线标定集 `{(s_i, d_i)}` 上，`d_i` = draft 与「新观测下全量模型输出」的动作差；选择阈值 `τ` 使接受的样本中 `P(d > ε) ≤ δ` 的置信上界成立（Clopper–Pearson/Conformal Risk Control）。若不存在这样的 `τ`，关闭投机。
- **延迟**：`L_resp = L_verify + (1−p)L_full`；`P = H + L_resp`；节省 `p(L_full − L_verify)`。验证路径含视觉编码 + grounding + 安全护盾；全量回退路径与基线相同。
- **anytime 回退**：若全量推理超过本轮 deadline，返回 draft 的**安全尾段**（慢速/保持）并标记 degraded；下一轮强制全量。目标是把 p99 与方差压在基线附近，而不是每轮都赌 draft。
- **缓存**：reset 期缓存指令/计划/静态场景 token；轮内只更新新图像与本体；接受 draft 时复用上一轮缓存特征。
- **准入控制**：GPU 利用率 > `U_max` 或 p99 超门禁时，降投机频率（每 k 轮一次）或关闭；draft 可抢占，验证与全量不可抢占。

### 技术可行性
- 中-高。prefetch 不需要新模型；draft 用同一 VLA（可减少 denoising 步数）；验证用已有 grounding + 轻量潜在预测；安全护盾是纯几何检查。
- 需要离线 replay 标定 `p`、`ε_fa`、`L_verify` 与 `τ`；需要真实 profile 才能确定 `L_full`、`L_draft`、`T_a` 的最优区间。

### 所需资源
- 离线 replay：1×A100 2–3 天；serving 工程 2 人周；部署 2×A100 80G（与 I6 共用）。

### 落地步骤
1. Profile 基线：`L_full`、`L_verify`、`L_draft` 随 `T_a`/分辨率/端口数的变化。
2. 离线构造轮次 tuple `(o_t, a_t, o_{t+1})`，生成 draft，统计 `p`、动作差、grounding 分离度。
3. 标定 `τ` 与 `ε_fa`；画 `τ ↔ p ↔ d` 的 Pareto 前沿。
4. 实现 prefetch + 验证 + 安全护盾 + anytime 回退；接 TDM 的 `ê_t/G_t`。
5. 接 TSA 准入控制；压测 N=3–5 端口的 p99/方差/stall 率。
6. 单任务通道 A/B：STE on/off、验证 on/off、draft 质量（全量/少步/缓存）、`T_a ∈ {4,8,16}`。

### 风险
- 验证器不可分 → 假接受伤成功率，或假拒绝使延迟爆炸（本轮最大风险；先离线标定再上真机）。
- 共享 GPU 下投机与回退争用 → p99 恶化（缓解：准入控制 + draft 可抢占 + 每端口预算）。
- 单模型边界：draft 必须是同一 VLA 的输出（少步/缓存），不能是第二个策略；若被裁定为「多模型」，降级为「同一模型的 checkpoint 变体」或关闭 STE。
- 动作统计规律性：draft 与全量输出的分布差异可能被评测端视为异常（缓解：只在验证通过时接受，安全护盾 + 动作健康度门禁）。

## 3. 修订后的 I6 v3：TSA 轮次感知 serving（原「确定性低延迟部署服务」）

- **保留**：共享 backend、每端口独立队列与 episode 状态隔离、fp8/INT8、torch.compile/CUDA Graph、obs 预取、`image_resize`、断线重连 + 健康探针。
- **新增 TSA（Turn Scheduler / Allocator）**：
  - 每端口维护 `(belief, draft, cache, deadline)`；`reset` 清空，跨端口不共享 episode 状态。
  - 请求分三类：**verification**（最高优先级，EDF）、**full fallback**（次高，连续批处理）、**draft prefetch**（最低，可抢占/可跳过）。
  - 准入：仅当 `GPU_util < U_max` 且本端口剩余执行窗口 `≥ L_draft` 时允许 draft；否则跳过，保 p99。
  - 门禁：验证路径 p99 < 40ms（以官方 15Hz/66ms 为动作级参照）；回退路径 p99 ≤ 基线全量推理的 1.1×；轮次 stall 率 <5%；动作健康度（界内/平滑/统计正常）0 拒绝。任一项超限 → 自动降投机频率或关闭。
- **轮次预算**：部署前用实测 `L_full`、`L_verify`、`p` 画 `T_a` 候选表；默认 `T_a=8`（`H≈0.53s`），接触任务/高险任务可试 `T_a=4`，长程搬运可试 `T_a=16`。最终由 I8 的 L1 析因决定。

## 4. 对既有创新点的增量修订

### I4 v3 人手干预 → barge-in + 轮次所有权
- 检测：手部检测（离散）+ 夹爪/本体异常（连续，F27）+ `obs_delta_indices` 历史栈。
- `T_a` 固定（F20）意味着服务端**不能中途抢占**已下发 chunk；「快速让位」只能靠：①当前 chunk 的**安全尾段**（最后几步慢速/保持）；②下一轮边界立即 `YIELD/HOLD`；③人离开后 `T_settle + grounding` 才恢复。
- 轮次所有权 `u_t` 由 TDM 维护；`YIELD` 是对话动作，不是第二个控制器。

### I5 v3 非标称示教合成 → REPAIR 库 + 子目标/效果标签
- v2 的扰动重放/跨段缝合继续；新增：
  1. **失败注入四式**：空闭合、错位闭合、早闭/晚闭、恢复拼接（失败段后接「后退-重对准-再抓」）。
  2. **自动标注**：夹爪开口（F27）+ 腕相机相对运动 + 得分点检测器，给每段打 `GRASP_OK/GRASP_FAIL/CONTACT/...` 与子目标完成标签。
  3. **REPAIR 库**：把「失败→修正」段按 `R_0/R_1/R_2` 分类，供 TDM 检索/条件化。
- 这些标签同时训练 TDM 的进度/效果头与 I7' 的潜在前向模型。

### I7' 世界模型 → 潜在前向验证器（转职，不裁撤）
- 不再做测试时 rollout/规划（与 PR6 冲突）。
- 降级为**轻量潜在前向模型**：从 `(z_t, a_t)` 预测 `ẑ_{t+1}`，只用于 STE 的一致性分数与 draft 预测；训练离线，推理 <5ms。
- 若连这个都超预算，直接用 TDM 的 `ê_t/G_t` 做验证器；WMA-0 的完整视频生成只用于离线合成（I5）。

### I8 v3 评测运营闭环 → 轮次级消融
- 保留 L0/L1/L2 与注册表；新增轮次级指标：`p`、`ε_fa`、`L_resp` p50/p99/var、stall 率、turns/episode、repair 率、probe 率、状态跟踪准确率、grounding 精确率/召回率。
- 新增安慰剂：
  - **P1 陈旧 draft**：不做验证直接接受 → 应在接触任务掉分。
  - **P2 打乱状态**：TDM 信念槽随机置换 → 应失去修复收益。
  - **P3 等算力不预取**：多跑一次模型但不隐藏延迟 → 隔离「额外算力」与「延迟隐藏」。
  - **P4 打乱观测验证**：验证器看错观测 → 应破坏接受率与正确性的相关。
- 预注册 + 序贯停止：先写假设、样本量、MDE；真机只测 top 2–3 候选；不把单任务通道当刷榜通道（F22）。

### I1/I2/I3/I9 的增量
- **I1**：增广器额外生成「世界意外变化」负样本（背景/外观/位置/遮挡/瞬移），用于标定 STE 验证器的分轴误报率。
- **I2**：共训数据按轮次质量加权；孪生任务提供更多子目标/效果弱标签；loader 加权 patch 不变。
- **I3**：接触/插入段的视觉伺服由 TDM 的 `CONTACT/INSERT` 子目标触发；伺服只作用在 chunk 的安全段，换相在轮次边界。
- **I9**：reset 检索同时提供三样东西：物体-技能先验（v1.1）、计划库条目（TDM）、目标物体重识别（REPAIR/PROBE）。共用同一嵌入索引与置信门控。

### 5.1 TDM 主循环（I10）

```python
class TurnDialogueManager:
    def reset(self, first_obs):
        self.plan = PLAN_LIBRARY.retrieve(
            instruction=first_obs["observation.language"],
            object_prior=self.retriever.lookup(first_obs),   # I9
        )                                                    # 离线计划库，无 per-turn LLM
        self.b = Belief(g=0, p=0.0, kappa="NONE", owner="R", t_left=T_BUDGET)
        self.prev_effect = None
        self.repair_level = 0
        self.consec_fail = 0

    def update(self, obs, last_chunk):
        f = self.features(obs)                               # 共享/轻量编码，<10ms
        e = self.effect_head(f, self.plan[self.b.g])         # 观测到的效果
        G = sim(self.plan[self.b.g].expected_effect, e) >= self.tau_g
        p = self.progress_head(f, self.plan[self.b.g])
        kappa = self.event_head(f, obs)                      # 接触/抓取/人手
        self.b = self.transition(self.b, G, p, kappa, obs)
        self.consec_fail = 0 if G else self.consec_fail + 1
        return self.select_act()

    def select_act(self):
        if self.b.owner == "H":                    return "YIELD"
        if self.done():                            return "TERMINATE"
        if self.b.t_left < T_MIN:                  return "COMMIT" if self.near_done() else "HOLD"
        if self.consec_fail >= N_G and self.repair_budget > 0:
            return "REPAIR"                        # R0→R1→R2 按连续失败升级
        if self.b.p >= self.tau_adv and self.pre(self.b.g + 1):
            return "ADVANCE"
        if self.b.ambiguous and self.probe_budget > 0:
            return "PROBE"
        return "CONTINUE"

    def prompt(self):
        g = self.plan[self.b.g]
        return dict(subgoal=g.name, expected_effect=g.expected_effect,
                    progress=self.b.p, last_outcome=self.last_outcome,
                    repair_level=self.repair_level)
```

### 5.2 STE 预取 / 验证 / 回退（I11）

```python
class SpeculativeTurnEngine:
    def after_send(self, obs_t, chunk_t, tdm):
        self.draft = None
        if not self.tsa.admit_draft(port=self.port):          # GPU 余量 + 窗口足够
            return
        g_next = tdm.predict_next_subgoal(chunk_t)
        self.draft = self.vla.generate(obs_t, prompt=g_next, steps="fast")
        self.pred_z = self.latent_fm.predict(obs_t, chunk_t)  # I7'，<5ms
        self.tdm_expect = tdm.plan[g_next].expected_effect

    def on_next_obs(self, obs_next, tdm):
        if self.draft is None:
            return self.full_infer(obs_next, tdm)
        z_next = self.encode(obs_next)                         # 验证本来就要编码
        g_score = tdm.grounding_score(self.tdm_expect, z_next)
        l_score = 1.0 - dist(self.pred_z, z_next)
        s = self.w_g * g_score + self.w_l * l_score
        if s >= self.tau and self.safety_shield(self.draft, obs_next):
            self.stats.accept()
            return self.residual_refine(self.draft, obs_next)  # 本体误差的廉价修正
        self.stats.reject()
        return self.full_infer(obs_next, tdm)                  # 世界给了意外 → 全量

    def full_infer(self, obs, tdm):
        try:
            return self.vla.generate(obs, prompt=tdm.prompt(),
                                     deadline=self.deadline)
        except DeadlineExceeded:
            self.stats.degraded()
            return self.safe_tail(self.draft, obs)             # anytime 回退
```

```python
class TurnScheduler:
    def admit_draft(self, port):
        return (self.gpu_util() < U_MAX and
                self.port_free_window(port) >= self.L_draft(port))

    def dispatch(self, req):
        if req.kind == "verify":       return self.edf_verify_heap.push(req)
        if req.kind == "full":         return self.continuous_batch.push(req)
        if req.kind == "draft":        return self.best_effort.push(req)

    def guard(self):
        if self.p99_verify > P99_TARGET or self.stall_rate > STALL_MAX:
            self.speculation_rate *= 0.5                       # 自动降投机
        if self.action_health_violations > 0:
            self.disable_speculation()                         # 门禁
```

```python
class TurnPolicyService:                 # 唯一参赛实体
    def reset(self):
        self.tdm.reset(self.first_obs)
        self.ste.reset()
        self.cache.reset()

                self.vla.generate(obs, prompt=self.tdm.prompt())
```

```python
def calibrate_verifier(turns, vla, tdm, eps_action, delta):
    scores, errors = [], []
    for (o_t, a_t, o_next) in turns:
        draft = vla.generate(o_t, prompt=tdm.predict_next_subgoal(a_t), steps="fast")
```

## 6. 关键推导

### 6.1 轮次率、延迟与 T_a 的三方权衡
- `H = T_a·Δt`；无投机 `P_0 = H + L_full`；有投机 `P = H + L_verify + (1−p)L_full`。
- 每轮节省 `ΔP = P_0 − P = p(L_full − L_verify) ≥ 0`；draft 计算只有在 `L_draft ≤ H` 且 GPU 有余量时才是「免费」的。
- 零等待/延迟隐藏区：`L_verify + (1−p)L_full ≪ H`，此时 `P ≈ H`，轮次率接近 `1/H`。
- **推论（投机买反馈带宽）**：若任务要求反馈延迟 `P ≤ D_max`，无投机需要 `H ≤ D_max − L_full`；有投机只需 `H ≤ D_max − L_resp`。因为 `L_resp < L_full`，投机允许**更小的 H**（更细的反馈）或**更大的任务容差**，等价于买到更高的反馈带宽。
- **T_a 的两难**：`H↓` → 反馈更细、轮次更多，但 `L_draft ≤ H` 更难满足、每轮调用更密；`H↑` → 预取更容易、调用更少，但反馈更粗。最优 `T_a` 由任务开环发散率 λ、容差 ε、`L_full`、`p(H)` 共同决定；用离线 replay 画 `T_a ↔ success_proxy ↔ p99` 的 Pareto 前沿，而非拍脑袋。

### 6.2 投机接受的选择性风险控制
- 设标定集 `{(s_i, d_i)}`，`d_i` 为 draft 与全量动作的差，`ε` 为可接受动作误差。对阈值 `τ`，接受集 `A(τ)={i: s_i≥τ}`，经验风险 `R̂(τ)=|{i∈A: d_i>ε}|/|A|`。
- 选 `τ` 使 `R̂(τ)` 的 `1−α` 置信上界（Clopper–Pearson）≤ `δ`；在可交换性假设下，测试集上的错误接受率 ≤ `δ`（有限样本修正项 `O(1/√n)`）。
- 若不存在可行 `τ`，说明验证器在该分布上不可分，**关闭投机**——这比「先上线再调」安全。
- 该框架把「投机加速」从工程技巧变成**可证伪的选择性预测问题**：报告 `p`、`ε_fa`、`τ`、标定集覆盖的 5 类泛化轴，缺一不可。

### 6.3 修复经济学
- 修复层级 `i` 的成功率 `q_i`、代价 `c_i`（轮次/时间），剩余价值 `V`。选最低 `i` 使 `q_i V / c_i ≥ λ`；若所有层级都不满足，转 `PROBE` 或 `YIELD`。
- 探测的信息价值：`VOI(a) = E[ΔH(b)|a] − λ c(a)`；仅当 `VOI > 0` 且探测预算未耗尽时执行，且 `a` 必须在安全、可逆包络内。
- 不可逆动作：`G_t ≥ τ_g^irr > τ_g`；若 grounding 不达标，先 `PROBE` 或退回上一个安全子目标，而不是赌。

## 7. 实验设计（分级、可证伪）

### 7.1 L0：离线 replay（免费、无限次）
- **数据**：官方 32 任务 episodes 按轮次切 `(o_t, a_t, o_{t+1})`；留出集按 episode 划分，避免同 episode 泄漏。
- **STE 标定**：生成 draft、计算 `s` 与 `d`；画 `τ ↔ p ↔ ε_fa` 的 Pareto；按任务族、接触/自由空间、5 类泛化轴分层报告。目标：在 `ε_fa ≤ 5%` 下 `p ≥ 0.6`（接触任务可放宽到 `p ≥ 0.4`，但 `ε_fa ≤ 2%`）。
- **TDM 状态**：在 5 个代表任务上人工标 3–6 个子目标/效果，测进度 MAE、grounding 精确率/召回率、误修复率。目标：标称场景误修复率 <2%，失败场景 grounding 召回 >80%。
- **延迟代理**：用实测 `L_full/L_verify/L_draft` 计算 `P`、`f_turn`、stall 率；不需要真机。

### 7.2 L1：分数因子设计（少量真机/单任务通道）
- 因子：TDM {on/off} × STE {on/off} × `T_a ∈ {4,8,16}` × 验证阈值 {保守/激进}。
- 主效应优先；交互项只测 L0 提示强的组合。通过判据：成功率不降、步骤分不降、p99 与方差在门禁内。
- 用同一初始场景做配对；报告效应量与置信区间，不只报均值。

### 7.3 L2：单任务通道确认 + 提交
- 只测 L0+L1 排名 top 2–3 候选；每候选 ≥2 任务 × 各 2 次。
- 任务选择：接触（PlugCharger/PlugInEthernet）、长程（OrganizeBookshelf/PackBag）、未见物品（StoreCups/PourOutMedicine）。
- 真机增益 ≥ 离线预测的 50% 才进入下一轮提交；否则回退。

### 7.4 安慰剂/反事实（证明因果，而不是相关）
| 臂 | 操作 | 预期 |
|---|---|---|
| P1 陈旧 draft | 不做验证，直接接受 | 接触任务成功率下降 |
| P2 打乱状态 | TDM 信念槽随机置换 | 修复收益消失 |
| P3 等算力不预取 | 多跑一次模型但不隐藏延迟 | 只有延迟变差、成功率不变 |
| P4 打乱观测验证 | 验证器看错观测 | 接受率与正确性去相关 |

### 7.5 指标与门禁
- 主指标：平均成功率（F22）；次指标：平均步骤分。
- 轮次级：`p`、`ε_fa`、`L_resp` p50/p99/var、stall 率、turns/episode、repair 率、probe 率、状态准确率、grounding P/R。
- 门禁：0 拒绝动作；动作健康度通过；验证路径 p99 < 40ms；回退路径 p99 ≤ 1.1× 基线；stall <5%；单任务通道不伤标称。

### 7.6 预注册与样本量
- 先写假设、主要终点、样本量、MDE、 stopping rule；真机 n 小，优先用配对/区组与步骤分方差缩减，但最终决策仍看成功率（F22）。
- 单任务通道只做实验台，不作为排行榜成绩（F22）。

## 9. 伦理 / 合规 / 单模型边界 checklist

- [ ] **不在评测时段做在线学习/适应**：TDM 阈值、STE 接受阈值、计划库、验证器权重全部赛前冻结；reset 期只做检索/缓存，不更新权重。
- [ ] **单模型边界（I10/I11）**：优选方案是 TDM 头共享 VLA 编码器、STE draft 为同一 VLA 的少步/缓存输出；不引入第二个任务策略。若组委会认定独立轻量头/潜在前向模型属于「多模型」，降级为：TDM 纯规则/FSM + prompt；STE 关闭或只用同一 checkpoint 的少步推理。**上计分通道前书面确认。**
- [ ] **延迟诚信**：不通过故意延迟、返回异常动作或伪造缓存来「美化」时延；报告 p99、方差、stall、`ε_fa`；动作健康度（界内/平滑/统计正常）为每次提交门禁。
- [ ] **人手在场**：barge-in 检测 → 安全尾段 + 下一轮 YIELD/HOLD；人离开 `T_settle` + 重新 grounding 才恢复；禁止在人手执行域内 PROBE。
- [ ] **数据使用**：官方 32 任务/110 语料/DiverseManip 均 apache-2.0；计划库/标定集注明来源；不使用评测集泄漏。
- [ ] **不可逆动作**：释放/倾倒/插到位要求更高 grounding 门槛；不达标时先 PROBE 或退回安全子目标。
- [ ] **机器人安全**：STE 的 draft 永不跳过安全护盾；全量回退路径保留；任何 draft 越界/超步长/夹爪异常一律丢弃。

## 11. 本轮最值得押注（一句话）

**押「轮次运行时」：I10 TDM 把一次性指令变成带信念/轮次/grounding/修复的内部对话，I11 STE 把下一轮推理藏进当前 chunk 的执行窗口——两者共用同一个 grounding 信号，形成「更好的状态 → 更准的 draft → 更低延迟 → 更多轮次」的正反馈；在成功率主键、`T_a` 固定、chunk 内无新观测的接口下，这是把「对话管理」从昂贵的奢侈品变成可负担的主干的最直接路径。**

## 12. 本轮最大风险（一句话）

**整个方案押在「grounding 能把『世界因我们的动作而变』与『世界因泛化/人手而变』分开」上；若这个谓词在 5 类泛化轴上不可分，STE 会假接受（修复被污染）或假拒绝（延迟爆炸），TDM 与 STE 会同时失效——所以 Q10/Q11 的离线标定必须先于任何真机投入。**
