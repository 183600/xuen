# 第 13 轮（新灵感循环第 1 轮）· IPD-VLA：把 30 步动作块编译成「意图程序」，用路径规划器展开，用蒸馏把慢意图变成快反射

> 日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮承接第 10 轮 **FACT-VLA**、第 11 轮 **GEO-RESIDUAL**、第 12 轮 **CHUNK-SERVO**；三个灵感词是「意图识别」「路径规划」「模型蒸馏」。本轮不推倒 CHUNK-SERVO 的「30 步规划 + 5 步伺服」，而是给它补上缺失的中间层：**VLA 的动作块到底想完成哪个子目标？这个子目标在当前几何下可不可达？能不能用一个 30Hz 的小头把 6B 模型的慢意图蒸馏出来？**

## 0. 先给结论：CHUNK-SERVO 让最后 3 厘米「有闭环」，但没有回答「闭环朝哪个子目标、走哪条路」

第 12 轮做对了一件关键的事：把 30 步开环 chunk 切成 5 步执行块，把接触段的反馈周期从 1 s 压到 167 ms。但它的闭环仍然只回答了「怎么修正」，没有回答三个更上位的问题：

1. **现在处于哪个阶段？** CHUNK-SERVO 对接近、对齐、插入、释放用同一套伺服增益；接触边界没有显式状态。
2. **这一步要去的子目标是什么？** 它从演示里检索「目标-夹爪相对位姿」，但检索到的目标可能被当前障碍物挡住、可能落在桌沿外、可能已经被移动；伺服只会在局部把夹爪拉向一个不可达的点。
3. **这条路可不可走？** VLA 的 30 步 chunk 是路径，不是「意图 + 几何」；如果桌面上多了一个杯子、人手伸进来、目标被挪了 10 cm，chunk 仍然按旧的世界模型开环执行。

所以本轮的押注是 **IPD-VLA（Intent–Path–Distill）**，中文叫「意图程序编译器」：

> **把 VLA 的 30 步动作块解析成一条低维「意图程序」——阶段 + 子目标 + 切换条件；用一个 30Hz 的小意图头把 6B 模型的慢意图蒸馏出来；用确定性路径规划器把子目标展开成当前场景下可走、可碰、可检查的几何路径；最后仍然用第 12 轮的 5 步视觉伺服收最后 3 厘米。**

一句话对比第 12 轮：**第 12 轮让最后 3 厘米「有闭环」；本轮让这个闭环知道「自己在哪个阶段、要去哪个子目标、路是否可走」。**

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **意图识别** | 从 VLA chunk 解析阶段/子目标；任务 DFA 约束的 Viterbi 解码；人类干扰意图（继续/让行/重规划） | 不加载第二个学习策略；不假设能拿到 VLA 内部 attention；不把意图当安全证书 |
| **路径规划** | 意图条件化的局部 RRT-Connect/A*；保守占据栅格；可行性投影；碰撞/人手/桌沿约束 | 不做全局 32 任务路径图；不做 30Hz 广域网重规划；不做无地图的纯反应式避障 |
| **模型蒸馏** | 把「慢 VLA + 解析器 + 规划器投影」蒸馏成 0.5M 参数的 30Hz 意图头；规划器在环的可行性蒸馏；DAgger 聚合 | 不蒸馏整个 6B 动作模型；不引入独立视觉编码器；不让蒸馏学生取代 VLA 的语义泛化 |

三个可验证创新点：

1. **意图程序解析（Intent Program Parsing）**：把 30×54 的 chunk 压缩成 `(z_k, g_k, τ_k)` 序列，用任务 DFA 约束的 Viterbi 解码；验证「显式阶段」是否比「隐式 chunk」更抗接触边界。
2. **规划器在环的可行性蒸馏（Planner-in-the-Loop Feasibility Distillation）**：教师标签不是 VLA 的原始子目标，而是被规划器投影到可行域后的子目标；学生学到「可执行的意图」，不是「听起来对的意图」。
3. **意图条件化融合（Intent-Conditioned Fusion）**：VLA 前馈、规划路径、视觉伺服按阶段加权；接近段信 VLA，插入段信规划/伺服，等待段信意图头；用同一个 5 步 API chunk 输出。

## 1. 直觉与动机

### 1.1 30 步动作块里真正重要的不是 30×54 个数字，而是几个子目标

官方 WLA 的 action head 输出 30 步、30 Hz、54 维的相对动作。把它看成一个矩阵，它是 30×54=1620 个数；但把它看成一条任务执行，它真正携带的信息只有：

- **阶段**：现在是在接近、对齐、抓取、搬运、插入、释放，还是回撤？
- **子目标**：这个阶段结束时，夹爪应该在哪里、朝哪个方向、夹爪开合多少？
- **切换条件**：什么时候算这个阶段完成？是距离小于 5 mm、夹爪电流突变、还是接触残差超过阈值？

剩下的 1600 多个数，很大程度上是「从当前位姿到子目标」的几何插值。几何插值恰恰是确定性规划器最擅长、VLA 最不擅长的事：规划器能看到当前点云、能检查碰撞、能按当前障碍物重算；VLA 只能按训练分布猜。

这就是 IPD-VLA 的第一个直觉：**不要把 VLA 的 chunk 当轨迹执行，要把它当「意图程序」编译。** 意图是低维的、慢变的、可检查的；轨迹是高维的、快变的、应该由当前几何决定的。

### 1.2 意图识别是缺失的接口

第 12 轮的伺服只知道「目标相对位姿」，不知道「现在该不该接触」。这会导致两个极端：

- 接近段用接触段的低增益 → 动作慢、超时；
- 插入段用接近段的高增益 → 撞、滑、过冲。

显式意图至少能带来三件事：

1. **阶段条件化的增益/约束**：接近段高增益、大步长；插入段低增益、法向缩幅；等待段零增益。
2. **阶段条件化的规划**：挂杯从上方接近，插网线沿插入轴接近，拉拉链沿切向走；这些不是一条直线能表达的。
3. **阶段条件化的恢复**：抓取失败 → 重抓；插入卡住 → 回撤 5 mm 再对；人移动目标 → 让行/重定位/重规划。

意图识别还覆盖**人的意图**：人伸手是要拿走目标、遮挡相机、递东西，还是只是路过？API 没有力/触觉，但四路 RGB + 本体足够做「动态残差 + 手部簇 + 时间持续性」的粗分类。粗分类不需要 100% 准确，只需要在「继续/让行/重规划」三档上保守。

### 1.3 路径规划是缺失的几何

CHUNK-SERVO 的路径就是 VLA chunk。它有两个问题：

- **VLA 看不见新障碍**：训练分布里没有「桌上多了一个杯子」「人手从右边伸进来」「目标被挪到桌沿」；chunk 仍然按旧分布走。
- **伺服是近视的**：IBVS/PBVS 只把夹爪拉向局部目标，不会绕开一个挡在中间的干扰物；它甚至会把「目标不可达」误判成「增益不够」。

局部路径规划器补的正是这一层：

- 用头部双目 + 腕部图建 5 mm 占据栅格；
- 按意图选约束（接近锥、插入轴、抓取球、等待区）；
- 用 RRT-Connect/A* 找一条当前场景下无碰撞的路径；
- 如果 VLA 的子目标不可达，把子目标投影到最近可行点；如果连可行点都没有，切 RECOVER。

这不是「用规划器取代 VLA」。VLA 仍然决定「去哪个语义子目标」；规划器只决定「在当前几何下怎么走过去」。两者分工，才是通才模型 + 确定性控制器的正确接口。

### 1.4 模型蒸馏是缺失的速度

6B WLA 在 24GB GPU 上跑一次 30 步 chunk 大约 100–300 ms；它不可能 30Hz 闭环。第 12 轮的解法是「30 步 plan + 5 步伺服」，但 5 步块内仍然没有新的语义意图；VLA 每秒才更新一次。

IPD-VLA 的解法是**蒸馏意图，不蒸馏动作**：

- 教师：6B VLA + 离线解析器 + 规划器可行性投影；
- 学生：0.5M 参数的 GRU/MLP 意图头，输入是缓存的 VLA 特征 + 本体 + 腕部低维描述子 + 距上次 VLA 查询的时间；
- 输出：阶段分布、子目标增量、置信度；
- 频率：30Hz，CPU <1 ms；
- 训练：DAgger 3–5 轮，规划器在环修正标签。

为什么蒸馏意图而不是动作？

1. **维度低**：意图只有 8 个阶段 + 6 个位姿增量 + 1 个置信度，样本效率高；
2. **慢变**：阶段在几百毫秒内不会跳变，学生不需要拟合高频接触动力学；
3. **可检查**：意图可以被 DFA 约束、被规划器投影、被置信度门控；动作蒸馏出来的学生错了很难发现；
4. **合规**：意图头是同一个 checkpoint 的附加头，不是第二个策略；规划器/伺服是确定性控制器，不是学习模型。

### 1.5 一个类比：VLA 是「慢解释器」，意图头是「编译器」，规划器是「代码生成」

- VLA 像 Python 解释器：语义强、泛化好，但每条动作都要「解释」一遍，慢。
- 意图程序像中间表示（IR）：低维、结构化、可优化。
- 蒸馏像编译器优化：把慢解释器的意图提取出来，生成一个快的本地代码（意图头）。
- 规划器像代码生成/寄存器分配：把 IR 展开成当前机器（当前场景）能执行的指令（路径）。
- 伺服像运行时检查：最后 3 厘米的边界检查。

这个类比也说明了风险：**编译器优化不能改变程序语义。** 如果意图解析错了，后面的规划/伺服越精确，错得越快。所以本轮把「意图切换的可验证性」放在第一位，而不是把「蒸馏精度」放在第一位。

## 2. 诊断：CHUNK-SERVO 的三个「不知道」

把一次接触失败拆开：

```text
t0: VLA 看到世界 → 输出 30 步 chunk
t0+0.1s: 执行第 1 个 5 步块；伺服把夹爪拉向检索到的相对目标
t0+0.27s: 执行第 2 个 5 步块；夹爪已经接近目标，但阶段仍是「接近」
t0+0.44s: 执行第 3 个 5 步块；应该切换到「插入」，但伺服增益没变
t0+0.61s: 接触发生；法向速度过大，滑/卡/过冲
t0+1.1s: VLA 才看到下一帧；已经晚了
```

三个「不知道」：

1. **不知道阶段**：没有显式的 `APPROACH/ALIGN/INSERT`，所以增益、约束、恢复策略不能按阶段切换。
2. **不知道子目标是否可达**：检索到的相对目标可能被障碍物挡住、在桌沿外、或者已经被移动；伺服仍然朝它拉。
3. **不知道路是否可走**：VLA chunk 是路径，不是「意图 + 当前几何」；新障碍/人手/目标移动不会改变 chunk。

第 12 轮的 5 步伺服解决了「反馈周期」，但没有解决「反馈朝向」。IPD-VLA 的三个层正好对应三个「不知道」：意图识别 → 阶段；路径规划 → 可达/可走；蒸馏 → 30Hz 的慢意图跟踪。

## 4. 方法：IPD-VLA

### 4.1 总架构

```text
                    ┌─────────────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1)         │
                    └──────────────┬──────────────────────────────┘
                                   │ websocket: obs / 5-step chunk
                                   ▼
                    ┌─────────────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)               │
                    │  ├─ intent head h_φ (30Hz, 0.5M)            │
                    │  ├─ task DFA + Viterbi                      │
                    │  ├─ local planner Π (5–10Hz)                │
                    │  ├─ visual servo (5-step)                   │
                    │  ├─ plan cache (30-step VLA plan)           │
                    │  └─ action adapter (WLA 54D → API 21D)      │
                    └──────────────┬──────────────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────────────┐
                    │  Shared VLA server (GPU)                    │
                    │  UnifoLM-WLA-1.0, 30-step teacher           │
                    └─────────────────────────────────────────────┘
```

- **唯一学习模型**：WLA checkpoint + 意图头（同一个 checkpoint 文件/同一 backbone 特征）；意图头不是第二个策略。
- **确定性控制器**：规划器 + 伺服；无学习权重。
- **数据资产**：33k 成功演示用于离线阶段标签/目标库；不是第二个模型。
- **教师/学生**：教师 = WLA + 解析器 + 规划器投影（离线/低频）；学生 = 意图头（在线/30Hz）。

### 4.2 意图程序：把 chunk 编译成 `(z, g, τ)`

定义任务语言 `l` 对应的 DFA：

```math
\mathcal A_l=(Z,z_0,\delta,F),\qquad Z=\{\text{APPROACH},\text{ALIGN},\text{GRASP},\text{LIFT},\text{TRANSPORT},\text{INSERT},\text{RELEASE},\text{RETREAT},\text{RECOVER},\text{WAIT}\}.
```

一条意图程序：

```math
P=((z_1,g_1,\tau_1),\ldots,(z_K,g_K,\tau_K)),
```

其中：

- `z_k ∈ Z`：阶段；
- `g_k ∈ SE(3) × [0,1]`：子目标（位置 + 姿态 + 夹爪开合）；
- `τ_k`：切换条件（持续时间、距离阈值、接触残差阈值、夹爪状态）。

解析器 `Ψ` 把 VLA chunk `a_{1:H}`、观测 `o`、语言 `l` 映射到意图程序：

```math
P^\star=\arg\max_{P\in\mathcal A_l}\ \sum_{k=1}^{K}\Big[
w_z\log p(z_k\mid a,o,l)
+w_g\,\|g_k-\hat g_k\|_\Sigma
+w_\tau\,\mathbb 1[\tau_k\text{ satisfied}]
\Big]+\text{transition prior}.
```

解析器是**离线/教师侧**的，可以慢：用动态规划在 30 步上找阶段边界（change-point Viterbi），复杂度 `O(H^2|Z|)`，`H=30` 时不到 1 万次运算。

阶段信号（不需要新模型）：

| 阶段 | 主要信号 | 子目标提取 |
|---|---|---|
| APPROACH | EE 速度高、夹爪开、距目标 >5cm | 阶段末 EE 位姿 |
| ALIGN | EE 减速、姿态误差下降、距目标 1–5cm | 对齐后的 EE 位姿 + 目标轴 |
| GRASP | 夹爪命令闭合、EE 速度低 | 夹爪闭合时的 EE 位姿 |
| LIFT/TRANSPORT | 夹爪闭合、EE 速度回升 | 阶段末 EE 位姿 |
| INSERT | 接触残差、沿轴速度、距目标 <1cm | 预接触位姿 + 插入轴 |
| RELEASE | 夹爪命令打开 | 释放位姿 |
| RETREAT | EE 远离目标 | 回撤位姿 |
| RECOVER/WAIT | 编辑检测、人手、规划失败 | 安全位姿/当前位姿 |

### 4.3 快意图头：0.5M 参数、30Hz、DFA 约束

学生 `h_φ`：

```math
(z_t,\Delta g_t,c_t)=h_\phi(x_t),\qquad g_t=T_t\circ\exp(\Delta g_t),
```

输入 `x_t`：

- `f_t`：上一次 VLA 查询缓存的视觉-语言特征（可选；没有就用零向量）；
- `q_t`：双臂关节/EE/夹爪/下身体本体（60 维以内）；
- `u_t`：腕部低维描述子（ORB 匹配数、颜色直方图、光流直方图、边缘密度，32 维）；
- `Δt`：距上次 VLA 查询的时间；
- `z_{t-1}`：上一阶段（one-hot）。

输出：

- `z_t`：10 类阶段 logits；
- `Δg_t ∈ R^6`：相对当前 EE 的子目标增量（xyz+rotvec）；
- `c_t ∈ [0,1]`：置信度。

DFA 约束解码：不是每帧取 argmax，而是在一个滑动窗口 `T=5` 上做 Viterbi：

```math
z_{1:T}^\star=\arg\max_{z_{1:T}}\ \sum_{t=1}^{T}\ell_t(z_t)
+\sum_{t=2}^{T}\log A_{z_{t-1},z_t},
\quad A_{ij}=\delta(i,j)\text{ 的平滑版本}.
```

复杂度 `O(T|Z|^2)=5×100=500`，可忽略。DFA 保证不会出现 `APPROACH → RELEASE` 这种非法跳变；同时把「接触边界」的抖动平滑掉。

训练损失：

```math
\mathcal L(\phi)=\mathbb E_{(x,z^\star,g^\star,c^\star)\sim\mathcal D}\Big[
\mathrm{CE}(z,z^\star)
+\lambda_g\|g-g^\star\|_\Sigma
+\lambda_c\mathrm{BCE}(c,c^\star)
\Big]+\lambda_s\mathcal R_{\text{smooth}}(\phi).
```

教师标签 `z^\star,g^\star` 来自：

1. 33k 成功演示的离线阶段分割（FACT-VLA CPT + GEO-RESIDUAL 接触信号）；
2. VLA chunk 的解析器 `Ψ`；
3. **规划器投影后的可行子目标**（见 4.5）。

### 4.4 路径规划器：意图条件化的局部规划

占据地图：

- 头部双目 + 腕部图 → 5 mm 体素；
- 机器人自身连杆按 URDF 掩码去掉；
- 障碍物按机器人半径 + 1 cm 膨胀；
- 透明/反光/细线用「置信度低 → 更保守膨胀」处理；置信度低于阈值时规划器直接返回失败，回退 VLA/伺服。

意图条件化的约束集 `C_z`：

| 意图 | 目标区域 | 姿态约束 | 速度/其他 |
|---|---|---|---|
| APPROACH | 球 `‖p-g‖≤2cm` | 工具轴锥 30° | `v≤5cm/s` |
| ALIGN | 球 `‖p-g‖≤1cm` | 工具轴锥 5° | `v≤2cm/s` |
| GRASP | 球 `‖p-g‖≤5mm` | 固定 | 夹爪按计划开合 |
| INSERT | 沿插入轴圆柱 `r≤2mm` | 轴锥 2° | `v≤2cm/s`，只允许目标接触 |
| RELEASE | 释放位姿 | 自由 | 夹爪打开 |
| RETREAT | 沿负接近方向 5cm | 自由 | `v≤5cm/s` |
| WAIT | 当前位姿 | 自由 | 零速度，远离人手可达集 |
| RECOVER | 安全位姿 | 自由 | 先停再重定位 |

规划代价：

```math
J(\xi)=\int_0^1\Big[
w_c\,c_{\text{coll}}(\xi(s),M_t)
+w_h\,c_{\text{human}}(\xi(s),H_t)
+w_z\,c_{\text{intent}}(\xi(s),z_t)
+w_s\|\xi''(s)\|^2
+w_l\|\xi'(s)\|
\Big]ds,
```

约束：

```math
\xi(0)=T_t,\quad \xi(1)\in\mathcal G_z(g_t),\quad
\xi(s)\in\mathcal F(M_t)\ \forall s,\quad
\xi\in\mathcal C_z.
```

算法：先试直线/圆弧 primitive；失败则 RRT-Connect（N=300，20ms 预算）+ shortcut 平滑 + 梯形速度参数化。返回 `ξ` 或 `⊥`。

**可行性投影**：如果 VLA 的子目标 `g` 不可达（在障碍里、在桌沿外、超出工作空间），规划器找最近可行子目标：

```math
\mathrm{Proj}_\Pi(g,z,M)=\arg\min_{g'\in\mathcal G_z(M)}\|g-g'\|_\Sigma,
```

其中 `G_z(M)` 是使 `Π(T,g',z,M)≠⊥` 的子目标集合。若 `G_z(M)=∅`，返回 `RECOVER`，不硬走。

### 4.5 规划器在环的可行性蒸馏

这是本轮最关键的训练细节。普通的意图蒸馏会让学生模仿 VLA 的原始子目标，但原始子目标可能几何不可行；学生学得越像，越会把不可行的意图复制到 30Hz 环里。

IPD-VLA 的教师标签是**可行性修正后的标签**：

```text
for each teacher sample (o, a_{1:H}, l):
    P = Ψ(a_{1:H}, o, l)                  # 解析意图程序
    for each (z_k, g_k, τ_k) in P:
        g_k' = Proj_Π(g_k, z_k, M(o))     # 规划器投影
        if g_k' == ⊥:
            z_k' = RECOVER; g_k' = safe_pose(o)
        else:
            z_k' = z_k; g_k' = g_k'
    add (x(o), z_k', g_k', c_k') to D
```

然后训练学生。这样学生学到的是「在当前几何下可执行的意图」，而不是「VLA 想象的意图」。规划器不是执行器，它是**几何可行性教师**。

DAgger 聚合：

1. 用演示 + VLA rollout 训练初始学生；
2. 在仿真/回放中跑学生，收集学生访问到的状态；
3. 在这些状态上查询教师（VLA + 解析器 + 规划器投影）；
4. 加入数据集，重训；
5. 重复 3–5 轮。

这解决了行为克隆的 compounding error：学生不是只在教师状态上训练，而是在自己会访问的状态上被纠正。

### 4.6 执行：意图条件化融合

每个 5 步块：

```text
z_t, g_t, c_t = h_φ(x_t)
z_t = DFA_Viterbi(z_t)
if c_t < θ_c or g_t invalid:
    a = VLA chunk fallback
else:
    ξ = Π(T_t, g_t, z_t, M_t)
    if ξ == ⊥:
        a = VLA chunk fallback / RECOVER
    else:
        a_ff = VLA plan[t:t+H_c]
        a_path = sample(ξ, H_c)
        Δ = servo(obs, g_t, z_t)
        a = fuse(a_path, a_ff, Δ, z_t)
```

融合公式（右乘，EE 局部系）：

```math
T_{\text{cmd}}[j]
=T_{\text{path}}[j]\circ
\exp\!\Big(
\beta_{z_t}\log\!\big(T_{\text{path}}[j]^{-1}T_{\text{ff}}[j]\big)
+\Delta_{\text{servo}}[j]
\Big),
```

其中 `β_z` 是阶段条件化的 VLA 信任权重：

| 意图 | `β_z` | 伺服增益 | 说明 |
|---|---:|---:|---|
| APPROACH | 0.7 | 高 | VLA 语义主导，规划器避障 |
| ALIGN | 0.5 | 中高 | 规划器姿态约束 + 伺服对齐 |
| GRASP | 0.1 | 低 | 规划器/夹爪主导 |
| INSERT | 0.2 | 低（法向缩幅） | 规划器轴约束 + 伺服微调 |
| RELEASE | 0.0 | 0 | 只开夹爪 |
| RETREAT | 0.3 | 中 | 规划器回撤 |
| WAIT | 0.0 | 0 | 保持，远离人手 |
| RECOVER | 0.0 | 0 | 先停再重定位 |

监控器：

- **进度残差**：`r_t = ‖T_t - g_t‖ - expected_progress`；连续 3 块不降 → 重规划/重查询 VLA。
- **置信度**：`c_t < θ_c` 连续 5 帧 → 回退 VLA chunk。
- **人手/编辑**：GEO-RESIDUAL 的 `edit_score > θ_e` → `WAIT/RECOVER`，先停再重定位。
- **接触异常**：`r_grasp` 突变 → 滑移 → 重抓/加大夹持。
- **规划失败**：连续 2 次 `⊥` → 回退 VLA chunk；连续 3 次 → `RECOVER`。

### 4.7 为什么能涨点

| 泛化轴 | 第 12 轮 CHUNK-SERVO | IPD-VLA 增量 |

| 位置 | 相对目标跟随受器移动 | 意图头 30Hz 更新子目标；规划器按当前几何重规划 |

| G9 | 单模型合规？ | 一个 checkpoint + 确定性控制器；材料写清 | 回退 C1 |

**2D 玩具验证（只检查接口逻辑，不代表真机成功率）**：

- 场景：4 个子目标的走廊，中间一个随机障碍；基线是「VLA 直线 chunk」，IPD 是「意图头 + 网格 A* 规划器」；
- 基线：成功率 **44%**，碰撞 **56%**；
- IPD（意图误差 ε=0）：成功率 **100%**；
- ε=1% / 2% / 5% / 10%：**96.5% / 94.0% / 83.5% / 62.5%**；
- 理论 `(1-ε)^4`：**96.1% / 92.2% / 81.5% / 65.6%**；玩具与理论基本吻合。

这个玩具说明两件事：

1. **规划器确实能把「语义对但几何不可行」的直线救回来**（44% → 100%）；
2. **意图误差按子目标数指数放大**（ε=5% 时 4 个子目标只剩 ~83%），所以本轮最大的风险不是规划器，而是意图切换。

## 7. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 意图边界错判 | 规划/伺服朝错误子目标 | DFA 约束、置信度门控、迟滞、多假设、VLA 重查询 |
| 规划器地图错 | 碰撞/卡住 | 保守膨胀、腕部深度、透明/细线置信度门控、回退伺服 |
| 蒸馏分布漂移 | 学生到 OOD 状态 | DAgger、置信度校准、教师重查询、规划器投影 |
| VLA/规划器冲突 | 路径抖动/超调 | 阶段条件化 `β_z`、限幅、冲突时回退 VLA |
| 单模型解释 | 被判定第二个模型 | C1/C2/C3；意图头同 checkpoint；规划/伺服确定性 |
| 延迟 | p99 超标 | 意图头 0.5M、规划 20ms、VLA 1Hz、5 步 chunk |
| DFA 覆盖不足 | 新任务无阶段序列 | 通用 DFA + VLA 先验；低置信度回退 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |

**合规三模式**：

- **C1 离线标注**：意图头只在离线生成阶段/子目标标签，线上只用 VLA + 确定性规划/伺服；最保守。
- **C2 确定性控制器**：意图头是同一 checkpoint 的附加头；规划/伺服无学习权重；主推。
- **C3 同 checkpoint 特征**：意图头使用 VLA 同一 encoder 的缓存特征，不加载第二个模型；需要强描述子时用。

**明确不做**：加载第二个学习策略/残差网络/独立视觉编码器做在线决策；把规划器训练成神经策略；用 30Hz 广域网跑 6B VLA。

**本轮最大风险一句话**：**意图头在「对齐→插入」边界错一帧，DFA 和规划器会把错误子目标「合法化」，伺服越准反而越快撞向错误位置；所以 IPD 的成败不在蒸馏精度，而在意图切换的可验证性。**

## 8. 一句话押注

**把 VLA 的 30 步动作块编译成「意图程序」，用规划器在环的可行性蒸馏训练一个 30Hz 的意图头，用意图条件化的局部路径规划展开子目标，用 5 步视觉伺服收最后 3 厘米——单模型不变，但系统第一次同时拥有慢语义、快意图和可检查的几何。**

## 1. 事实核对

### 1.1 提交 API：chunk 语义（A，2026-10-31 复核）

重新读取 `unibot_submission/main/README.md`：

- `action_chunk_size`（记为 `T_a`）是每次 `get_action` 返回的 leading time-axis 长度；
- index 0 先执行，其余按顺序执行，直到 evaluator 再次调用 `get_action`；
- chunk 内没有新观测，也没有打断机制；
- `control_space` 仅 `joint` 或 `ee`，二者互斥；
- `ee` 动作是 base 系绝对目标位姿 `xyz(3)+rpy(3)`；
- `action.pivot` 是 7 维共享动作，README 未逐维定义；
- 观测四路 RGB 480×640，无 depth/camera_info/force/tactile；
- README **没有写死控制频率**；30Hz 是 WLA 的 `target_fps`，不是 evaluator 承诺。

**推论**：第 12 轮的「1 秒开环」问题仍然成立，但 `f_c=30Hz` 必须实测。若 `f_c=10Hz`，`H_c=5` 的反馈周期是 500ms+τ，必须降到 `H_c=3` 或只做 PBVS。

| 项 | 值 |

### 1.5 对设计的硬约束

1. **单模型**：部署侧只能有一个学习模型；意图头必须挂在同一个 checkpoint 上，规划/伺服必须无学习权重。

## 2. 问题形式化

### 2.1 POMDP

定义部分可观测马尔可夫决策过程：

```math
\mathcal M=(\mathcal S,\mathcal A,\mathcal O,T,\Omega,R,\gamma),
```

- 观测 `o_t=(I_t^{head},I_t^{wrist},q_t,l)`；
- 动作 `a_t=(\Delta T_t,u_t)\in SE(3)\times[0,1]`（EE 相对位姿 + 夹爪）；
- 语言 `l` 给定任务；
- 成功指标 `y∈{0,1}`，单任务 `p_t=1/10∑ y`，总分 `S=1/32∑ p_t`。

VLA 策略：

```math
\pi_\theta(a_{t:t+H}\mid o_t,l),\qquad H=30.
```

### 2.2 意图程序

**定义 1（意图程序）**：给定任务 DFA `A_l=(Z,z_0,δ,F)`，长度 `K` 的意图程序是

```math
P=((z_1,g_1,\tau_1),\ldots,(z_K,g_K,\tau_K)),
```

满足：

1. `z_0→z_1→…→z_K` 是 `A_l` 中的合法路径；
2. `g_k=(p_k,R_k,u_k)\in SE(3)\times[0,1]` 是子目标（位置、姿态、夹爪开合）；
3. `τ_k` 是切换条件：持续时间、距离阈值、接触残差阈值或夹爪状态。

**定义 2（解析器）**：

```math
\Psi(a_{1:H},o,l)=\arg\max_{P\in\mathcal A_l}\ \sum_{k=1}^{K}\Big[
w_z\log p(z_k\mid a,o,l)
+w_g\|g_k-\hat g_k\|_\Sigma
+w_\tau\mathbb 1[\tau_k\text{ satisfied}]
\Big]+\text{prior}(P).
```

解析器是教师侧的离线模块，可以慢；它把 30×54 的 chunk 压缩成 `K` 个三元组。

### 2.3 任务 DFA

每个任务一个 DFA；示例：

**HangCup**：

```text
APPROACH → ALIGN → GRASP → LIFT → TRANSPORT → ALIGN_HANG → HANG → RELEASE → RETREAT
```

**PlugInEthernet**：

```text
APPROACH → ALIGN → GRASP → LIFT → TRANSPORT → ALIGN_INSERT → INSERT → RELEASE → RETREAT
```

**ZipUp**：

```text
APPROACH → ALIGN → GRASP → PULL → FOLLOW_ZIP → RELEASE → RETREAT
```

DFA 的作用：

- 禁止非法跳变（如 `APPROACH→RELEASE`）；
- 给 Viterbi 一个强先验，降低接触边界的抖动；
- 给规划器一个阶段序列，避免「一步规划到最终目标」。

未见过/未建模的任务使用通用 DFA：所有阶段允许，但 `RELEASE` 必须在 `GRASP` 之后，`INSERT` 必须在 `ALIGN` 之后。

### 2.4 规划器

**定义 3（意图条件化规划）**：给定当前 EE 位姿 `T_t`、子目标 `g_t`、意图 `z_t`、局部地图 `M_t`，规划器返回路径 `ξ:[0,1]→SE(3)` 或 `⊥`：

```math
\xi=\Pi(T_t,g_t,z_t,M_t),
```

满足：

```math
\xi(0)=T_t,\quad \xi(1)\in\mathcal G_{z_t}(g_t),\quad
\xi(s)\in\mathcal F(M_t)\ \forall s,\quad
\xi\in\mathcal C_{z_t}.
```

- `G_z(g)`：意图条件化的目标区域（球/圆柱/锥）；
- `F(M)`：保守占据地图的自由空间；
- `C_z`：意图条件化的姿态/速度/接触约束。

**定义 4（可行性投影）**：

```math
\mathrm{Proj}_\Pi(g,z,M)=\arg\min_{g'\in\mathcal G_z(M)}\|g-g'\|_\Sigma,
```

其中 `G_z(M)={g':Π(T,g',z,M)≠⊥}`。若 `G_z(M)=∅`，返回 `⊥`（RECOVER）。

### 2.5 学生与蒸馏

**定义 5（意图头）**：

```math
(z_t,\Delta g_t,c_t)=h_\phi(x_t),\qquad g_t=T_t\circ\exp(\Delta g_t),
```

输入 `x_t=(f_t,q_t,u_t,\Delta t,z_{t-1})`：

- `f_t`：上次 VLA 查询缓存的视觉-语言特征（可选）；
- `q_t`：本体（EE/关节/夹爪/下身体，≤60 维）；
- `u_t`：腕部低维描述子（ORB 匹配数、颜色直方图、光流直方图、边缘密度，32 维）；
- `Δt`：距上次 VLA 查询的时间；
- `z_{t-1}`：上一阶段 one-hot。

**定义 6（蒸馏损失）**：

```math
\mathcal L(\phi)=\mathbb E_{(x,z^\star,g^\star,c^\star)\sim\mathcal D}\Big[
\mathrm{CE}(z,z^\star)
+\lambda_g\|g-g^\star\|_\Sigma
+\lambda_c\mathrm{BCE}(c,c^\star)
\Big]+\lambda_s\mathcal R_{\text{smooth}}(\phi),
```

其中 `z^\star,g^\star` 是**规划器投影后的教师标签**，不是 VLA 原始子目标。

### 2.6 分层策略

```math
\pi_{\text{IPD}}(a_{t:t+H_c}\mid o_t)
=\mathrm{Execute}\Big(
\Pi\big(T_t,h_\phi(x_t),M_t\big),
\pi_\theta(a_{t:t+H}\mid o_t,l),
\mathrm{Servo}(o_t,g_t,z_t)
\Big).
```

执行器只返回 `H_c=5` 步；`H=30` 的 VLA plan 在后台缓存/异步更新。

### 2.7 误差预算

设每个子目标的意图正确率为 `p_z`、规划器成功率为 `p_p`、伺服跟踪成功率为 `p_s`，且暂假设独立，则 `K` 个子目标的成功概率（无恢复）为：

```math
P_{\text{success}}\approx(p_z p_p p_s)^K.
```

| 场景 | `p_z` | `p_p` | `p_s` | 单子目标 | `K=4` |
|---|---:|---:|---:|---:|---:|
| 乐观 | 0.99 | 0.99 | 0.97 | 0.951 | **0.818** |
| 目标 | 0.98 | 0.99 | 0.97 | 0.941 | **0.784** |
| 保守 | 0.95 | 0.95 | 0.95 | 0.857 | **0.539** |
| 玩具 ε=5% | 0.95 | 1.00 | 1.00 | 0.950 | **0.815**（实测 0.835） |

这个表是**设计预算**，不是保证。它说明：意图层的 1–2pp 误差，经过 4 个子目标会放大到 5–10pp；所以本轮把意图切换的可验证性放在第一位。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
                    ┌─────────────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1)         │
                    └──────────────┬──────────────────────────────┘
                                   │ websocket: obs / 5-step chunk
                                   ▼
                    ┌─────────────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)               │
                    │  ├─ intent head h_φ (30Hz, 0.5M)            │
                    │  ├─ task DFA + Viterbi                      │
                    │  ├─ local planner Π (5–10Hz)                │
                    │  ├─ visual servo (5-step)                   │
                    │  ├─ plan cache (30-step VLA plan)           │
                    │  └─ action adapter (WLA 54D → API 21D)      │
                    └──────────────┬──────────────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────────────┐
                    │  Shared VLA server (GPU)                    │
                    │  UnifoLM-WLA-1.0, 30-step teacher           │
                    └─────────────────────────────────────────────┘
```

- 每个端口一个 `PolicyService`，独立 `reset()`、独立意图状态、独立规划器种子、独立 plan cache。
- 意图头/规划器/伺服是 CPU 线程；VLA 请求异步、可批处理。
- 共享 VLA server 用 session ID 区分端口；权重只有一份，不违反单模型。
- 意图头权重是 WLA checkpoint 的一部分（附加 head），不是独立模型文件。

### 3.2 时间预算

| 组件 | 频率 | 单次耗时（目标） | 说明 |
|---|---:|---:|---|
| 意图头 | 30Hz | <1ms | 0.5M GRU/MLP，CPU |
| DFA Viterbi | 每 chunk | <0.1ms | `T=5,|Z|=10` |
| 规划器 | 5–10Hz | 10–30ms | RRT-Connect N=300 + shortcut |
| 伺服 | 每 chunk | 1–5ms | ORB/轮廓 + PBVS |
| VLA | 1Hz | 100–300ms GPU | 6B bf16，异步 |
| 网络 RTT | 每 chunk | 20–150ms | 远程 API |
| **端到端反馈** | `H_c=5` | **~200–320ms** | `5/30 + RTT + 规划/伺服` |

若 `f_c=10Hz`：`T_fb=5/10+τ≈500ms+τ`；此时把 `H_c` 降到 3，或关闭规划器只做 PBVS。

### 3.3 API 适配

`ee` 模式返回：

```python
{
    "meta.token": token,
    "action.left_gripper":  np.float32 (5,1),
    "action.right_gripper": np.float32 (5,1),
    "action.pivot":         np.float32 (5,7),
    "action.left_ee_pose_gripper_base":  np.float32 (5,6),  # absolute xyz+rpy
    "action.right_ee_pose_gripper_base": np.float32 (5,6),  # absolute xyz+rpy
}
```

WLA 54D → 挑战赛 21D：

1. `left_ee_rel[6]` compose 到当前左 EE 绝对位姿 → `left_ee_abs[6]`（转 xyz+rpy）；
2. `right_ee_rel[6]` 同理；
3. gripper 直通（校验 0–1 方向）；
4. `pivot=[vx,vy,wz,yaw,pitch,roll,height]` 从 WLA base/waist 组合；具体符号/顺序必须用 `example_env.py` 和单任务通道验证；
5. 若 `pivot` 语义不一致，先返回全零 pivot，只验证双臂。

**关键细节**：WLA 的每个未来动作是「相对 plan-time 当前 EE」的位姿，不是累积增量；adapter 必须先把整个 30 步 compose 成 base 系绝对目标，再按 5 步切片。

### 3.4 状态机

```text
INIT ──first obs──▶ PLAN ──plan ready──▶ INTENT
  ▲                   ▲                    │
  │                   │                    ├─ z=APPROACH/ALIGN ──▶ PATH
  │                   │                    ├─ z=GRASP/INSERT ────▶ CONTACT
  │                   │                    ├─ z=WAIT ────────────▶ HOLD
  │                   │                    └─ z=RECOVER ─────────▶ RECOVER
  │                   │                                              │
  │                   └── replan ◀── monitor ◀── progress residual ──┘
  └──────────────────────────────────────────────────────────────────┘
```

- `PATH`：规划器路径 + VLA 前馈 + 伺服；
- `CONTACT`：法向缩幅、切向保留、意图条件化低增益；
- `HOLD`：零速度，远离人手可达集；
- `RECOVER`：先停、重定位、重查询 VLA、再规划。

## 4. 意图识别

### 4.1 解析器：阶段边界 Viterbi

给定 chunk `a_{1:H}` 和观测 `o`，先算每步的阶段打分：

```math
s_t(z)=w_g g_t^{\text{grip}}+w_v v_t^{\text{prof}}+w_d d_t^{\text{dist}}+w_c c_t^{\text{contact}}+w_\tau \tau_t,
```

其中：

- `g_t^grip`：夹爪命令的闭合/打开/保持；
- `v_t^prof`：EE 速度/加速度曲线；
- `d_t^dist`：到目标/受器的距离（头双目 + 第 12 轮几何）；
- `c_t^contact`：GEO-RESIDUAL 的接触/编辑残差；
- `τ_t`：时间先验（阶段典型持续时间）。

阶段边界 `0=b_0<b_1<…<b_K=H` 的 Viterbi：

```math
\max_{b_1<\cdots<b_K}\ \sum_{k=1}^{K}\sum_{t=b_{k-1}+1}^{b_k}s_t(z_k)
+\sum_{k=2}^{K}\log A_{z_{k-1},z_k}.
```

复杂度 `O(H^2|Z|)`；`H=30`、`|Z|=10` 时不到 1 万次运算，离线可忽略。

### 4.2 阶段信号与子目标提取

| 阶段 | 进入条件 | 子目标 `g_k` | 切换 `τ_k` |
|---|---|---|---|
| APPROACH | 距目标 >5cm；夹爪开 | 阶段末 EE 位姿 | 距目标 ≤5cm |
| ALIGN | 距目标 1–5cm；姿态误差下降 | 对齐位姿 + 目标轴 | 姿态误差 ≤5° |
| GRASP | 夹爪闭合命令 | 闭合时 EE 位姿 | 夹爪到位/电流阈值 |
| LIFT | 夹爪闭合；EE 上升 | 抬起位姿 | 离台面 ≥2cm |
| TRANSPORT | EE 向放置点移动 | 预放置位姿 | 距放置点 ≤5cm |
| INSERT | 接触残差；沿轴速度 | 预接触位姿 + 插入轴 | 接触稳定/深度到位 |
| RELEASE | 夹爪打开命令 | 释放位姿 | 夹爪打开 |
| RETREAT | EE 远离目标 | 回撤位姿 | 离目标 ≥5cm |
| RECOVER | 编辑/滑移/规划失败 | 安全位姿 | 重定位完成 |
| WAIT | 人手/遮挡 | 当前位姿 | 人手离开 |

子目标提取原则：

- 刚体接触：取「首次接触前 1–3 帧」的 EE 位姿 + 目标轴；
- 抓取：取夹爪闭合瞬间的 EE 位姿；
- 放置/挂/叠：取「目标进入腕部视野且距离 <5cm」的位姿；
- 变形任务：只取相位，不取精确子目标；规划器不启用。

### 4.3 学生架构

```text
x_t = [f_t (optional), q_t, u_t, Δt, z_{t-1}]
        │
        ├─ Linear(→256) + ReLU
        ├─ GRU(256, 256)  ×2
        │
        ├─ head_z: Linear(256→10)        # phase logits
        ├─ head_g: Linear(256→6)         # Δg (xyz+rotvec)
        └─ head_c: Linear(256→1) + sigmoid  # confidence
```

- 参数量：约 0.5M；
- 推理：<1ms CPU（batch=1）；
- 训练：单 GPU 数小时；数据 33k 演示 + DAgger rollout；
- 量化：int8 可选，进一步降 CPU。

### 4.4 DFA 约束 Viterbi

给定学生 logits `ℓ_t(z)` 和 DFA 转移矩阵 `A`：

```math
z_{1:T}^\star=\arg\max_{z_{1:T}}\sum_{t=1}^{T}\ell_t(z_t)+\sum_{t=2}^{T}\log A_{z_{t-1},z_t}.
```

实现：

```python
def viterbi(logits, A, z_prev):
    # logits: T x |Z|; A: |Z| x |Z| (log-prob)
    dp = logits[0] + logA_prior[z_prev]
    back = []
    for t in range(1, T):
        scores = dp[:, None] + A
        best = scores.argmax(axis=0)
        dp = scores[best, np.arange(len(best))] + logits[t]
        back.append(best)
    # backtrack...
```

- 非法转移 `A_ij=-inf`；
- 未建模任务用平滑的通用 DFA；
- 输出阶段序列，取当前帧 `z_t` 作为执行意图。

### 4.5 人类意图

人类意图不是「识别是谁」，而是「判断要不要让」：

| 信号 | 计算 | 判定 |
|---|---|---|
| 动态残差 | 双目点云自运动补偿后，去掉 URDF 自身连杆，剩余动态簇 | 有外部运动 |
| 手部簇 | 动态簇的尺寸/高度/速度在人类手部范围 | 人候选 |
| 时间持续性 | 同一簇连续 `K` 帧存在 | 升格为人 |
| 目标关系 | 人手簇与目标/机器人路径的距离 | 干扰/递物/路过 |

响应策略：

```text
if human_detected and distance_to_path < d_safe:
    z = WAIT
    plan retreat to safe pose
    if human_leaves: z = RECOVER → re-localize → replan
elif human_moves_target:
    z = RECOVER
    re-localize target; re-query VLA
else:
    continue
```

**不声称 100% 检测**；人手不在视野时用本体/夹爪/编辑残差兜底。

### 4.6 训练标签与校准

标签来源：

1. 33k 成功演示的离线阶段分割（FACT-VLA CPT）；
2. 接触/编辑信号（GEO-RESIDUAL）；
3. VLA chunk 解析器 `Ψ`；
4. 规划器投影后的可行子目标。

校准：

- 温度缩放（temperature scaling）校准 `c_t`；
- 用 held-out 任务的 ECE 评估；
- 置信度低于 `θ_c` 时回退 VLA；
- 阶段后验熵高于阈值时，不做硬切换，保持上一阶段。

## 5. 路径规划

### 5.1 占据地图

- 头部双目：`fx≈282 px`，基线 58.2526 mm；0.5–1.0 m 工作距离视差 16–33 px；
- 腕部：无内参，先棋盘格标定；标定前只用头部双目；
- 体素：5 mm；
- 机器人自身：URDF + 关节角 → 连杆掩码；
- 膨胀：机器人半径 + 1 cm；
- 透明/反光/细线：置信度低 → 膨胀加倍；置信度低于阈值 → 规划器返回 `⊥`。

### 5.2 约束

| 意图 | 目标区域 `G_z` | 姿态约束 | 速度/接触 |
|---|---|---|---|
| APPROACH | 球 2cm | 工具轴锥 30° | `v≤5cm/s` |
| ALIGN | 球 1cm | 工具轴锥 5° | `v≤2cm/s` |
| GRASP | 球 5mm | 固定 | 夹爪按计划 |
| INSERT | 圆柱 `r≤2mm` | 轴锥 2° | `v≤2cm/s`，只允许目标接触 |
| RELEASE | 释放位姿 | 自由 | 夹爪打开 |
| RETREAT | 负接近方向 5cm | 自由 | `v≤5cm/s` |
| WAIT | 当前位姿 | 自由 | 零速度，远离人手 |
| RECOVER | 安全位姿 | 自由 | 先停再重定位 |

### 5.3 代价

```math
J(\xi)=\int_0^1\Big[
w_c c_{\text{coll}}+w_h c_{\text{human}}+w_z c_{\text{intent}}
+w_s\|\xi''\|^2+w_l\|\xi'\|
\Big]ds.
```

- `c_coll`：占据概率的 upper confidence bound；
- `c_human`：人手可达集/动态簇的距离惩罚；
- `c_intent`：阶段约束（插入轴距离、姿态误差、接近方向）；
- `w_s`：平滑；
- `w_l`：路径长度。

### 5.4 算法

```python
def plan(T0, g, z, M):
    G = goal_region(g, z)          # ball / cylinder / cone
    if straight_or_arc_feasible(T0, G, M, z):
        return time_parameterize(shortest_primitive(T0, G))
    tree_a, tree_b = {T0}, {sample(G)}
    for i in range(N=300):
        T_rand = sample_state(z)
        T_a = nearest(tree_a, T_rand)
        T_new = steer(T_a, T_rand)
        if collision_free(T_a, T_new, M, z):
            tree_a.add(T_new)
            if connect(tree_b, T_new):
                path = extract(tree_a, tree_b)
                return time_parameterize(shortcut(path))
        swap(tree_a, tree_b)
    return None
```

- 先试直线/圆弧，覆盖大多数桌面任务；
- 失败才 RRT-Connect，N=300，20ms 预算；
- shortcut 平滑；
- 梯形速度参数化，尊重关节限位/速度/加速度；
- 返回 `ξ` 或 `None`。

### 5.5 可行性投影

```python
def project(g, z, M):
    if plan(current, g, z, M) is not None:
        return g
    # sample feasible subgoals in a ball around g
    for g2 in sample_ball(g, r=5cm, n=50):
        if plan(current, g2, z, M) is not None:
            return g2
    return None  # RECOVER
```

- 投影半径按任务/阶段设（APPROACH 5cm，INSERT 1cm）；
- 投影后的子目标作为教师标签；
- 若连续投影失败，切 RECOVER，不硬走。

### 5.6 复杂度

- 碰撞检查：`O(M)`，`M=5000` 点；
- RRT-Connect：`O(N log N + N M)`；`N=300`，`M=5000` → 约 1.5M 次距离检查，20ms 内可完成（C++/numpy 向量化）；
- 每 chunk 一次规划；`H_c=5` @30Hz → 6Hz 规划，CPU 占用约 12–18% 单核；
- 多端口：规划器每端口独立；共享 VLA；CPU 核数 ≥ 端口数 × 1。

## 6. 蒸馏

### 6.1 教师/学生

| 角色 | 组成 | 频率 | 是否部署 |
|---|---|---|---|
| 教师 | 6B WLA + 解析器 `Ψ` + 规划器投影 `Proj` | 1Hz/离线 | VLA 部署；解析器/投影离线 |
| 学生 | 0.5M 意图头 `h_φ` | 30Hz | 部署（同一 checkpoint 附加头） |
| 执行器 | 规划器 + 伺服 | 5–10Hz/每 chunk | 部署（确定性） |

### 6.2 可行性感知标签

```text
for each teacher sample (o, a_{1:H}, l):
    P = Ψ(a_{1:H}, o, l)
    for each (z_k, g_k, τ_k) in P:
        g_k' = Proj_Π(g_k, z_k, M(o))
        if g_k' is None:
            z_k' = RECOVER; g_k' = safe_pose(o)
        else:
            z_k' = z_k; g_k' = g_k'
        c_k' = 1 if g_k' reachable and phase succeeds else 0
        add (x(o), z_k', g_k', c_k') to D
```

关键：**教师标签不是 VLA 原始意图，而是规划器可行性修正后的意图。** 这样学生学到的是「可执行意图」，不是「想象意图」。

### 6.3 损失

```math
\mathcal L(\phi)=\mathbb E_{\mathcal D}\Big[
\mathrm{CE}(z,z^\star)
+\lambda_g\|g-g^\star\|_\Sigma
+\lambda_c\mathrm{BCE}(c,c^\star)
\Big]+\lambda_s\|\phi\|^2.
```

超参建议：

- `λ_g=1.0`（位置以 cm 归一化，旋转以 rad 归一化）；
- `λ_c=0.5`；
- `λ_s=1e-4`；
- 阶段类别不平衡：按任务/阶段频率加权；
- 置信度校准：温度缩放。

### 6.4 DAgger

```text
D_0 = demos + VLA rollouts
φ_0 = train(D_0)
for i in 1..R:
    run π_{φ_{i-1}} in sim/replay
    S_i = visited states
    for s in S_i:
        query teacher (VLA + Ψ + Proj) at s
        add (x(s), z*, g*, c*) to D_i
    φ_i = train(D_0 ∪ ... ∪ D_i)
```

- `R=3–5`；
- 仿真/回放中用同一 WLA；不需要真机；
- 每轮数据量控制在 50k–100k 样本，避免训练爆炸；
- 用任务/阶段分层采样，防止简单任务主导。

### 6.5 理论边界

**命题 1（DFA 合法性）**：Viterbi 输出 `z_{1:T}^⋆` 一定被 `A_l` 接受。证明：递推只允许 `A_{ij}>-∞` 的转移，终态取 `F` 中最大；构造性成立。

**命题 2（规划可行性）**：若 `Π` 返回 `ξ`，则 `ξ` 在保守地图 `M` 的自由空间内，且终点在 `G_z(g)`。证明：碰撞检查/目标采样按定义构造；`shortcut` 只接受无碰撞路径。

**命题 3（蒸馏误差，DAgger）**：在标准 DAgger 假设下（损失强凸、在线学习器无遗憾），学生平均意图误差为 `O(ε+γ)`，其中 `ε` 是教师标签噪声、`γ` 是在线遗憾。证明：Ross et al. 2011 的标准结果；本报告只给假设与引用，不重复证明。

**命题 4（分层成功下界）**：若每个子目标的意图/规划/伺服成功概率分别为 `p_z,p_p,p_s` 且独立，则 `K` 个子目标全成功的概率为 `(p_z p_p p_s)^K`。证明：链式法则；独立性是保守设计假设，不是现实保证。

**命题 5（性能差）**：设教师策略 `π_T`、学生策略 `π_S`，若学生意图/子目标误差 ≤`ε`，规划器展开对值函数是 `L`-Lipschitz，则

```math
|J(\pi_S)-J(\pi_T)|\le \frac{L\varepsilon}{1-\gamma}+O(\text{planner failure}).
```

证明：性能差引理 + Lipschitz 优势函数；这是相对教师的界，不是相对最优策略的界。

### 6.6 实现细节

- 学生输入 `f_t` 可选：若 VLA 不暴露特征，用零向量；只用本体 + 腕部描述子也能跑，但准确率下降；
- 腕部描述子用固定算法（ORB/颜色/光流），不是学习编码器；
- 学生不加载第二套视觉 backbone；
- 训练/推理同一 checkpoint 文件；部署时 `torch.load` 一次，意图头是 `state_dict` 的一部分；
- 若官方要求「一个模型文件」，把意图头权重合并进 WLA checkpoint 的 `state_dict`，加载时按 key 分派。

## 7. 执行与融合

### 7.1 chunk 循环

```python
class IPDvla:
    def get_action(self, obs):
        self._tick(obs)
        self._maybe_query_vla(obs)          # async, 1Hz
        z, dg, c = self.student(self._features(obs))
        z = self.dfa.viterbi(z)             # constrained decoding
        g = compose(self.obs.ee, dg)
        if c < self.theta_c or not self._valid(g):
            return self._fallback(obs)
        xi = self.planner.plan(self.obs.ee, g, z, self.obs.map)
        if xi is None:
            return self._fallback(obs)
        a_ff = self._vla_chunk(obs)         # 5 steps
        a_path = self._sample(xi, self.H_c)
        delta = self.servo.compute(obs, g, z)
        a = self._fuse(a_path, a_ff, delta, z)
        self._monitor(obs, z, g)
        return self.adapter(a, obs)
```

### 7.2 融合

```math
T_{\text{cmd}}[j]
=T_{\text{path}}[j]\circ
\exp\!\Big(
\beta_z\log(T_{\text{path}}[j]^{-1}T_{\text{ff}}[j])
+\Delta_{\text{servo}}[j]
\Big).
```

- `T_ff[j]`：VLA 相对动作 compose 到 plan-time 当前 EE；
- `T_path[j]`：规划路径第 `j` 个采样；
- `Δ_servo[j]`：视觉伺服修正（EE 局部系）；
- `β_z`：阶段信任权重；
- 限幅：`‖Δ_servo‖≤1cm`，`‖Δ_rot‖≤0.05rad`。

### 7.3 阶段权重

| 意图 | `β_z` | `K_p` | `K_d` | 备注 |
|---|---:|---:|---:|---|
| APPROACH | 0.7 | 0.8 | 0.1 | VLA 主导 |
| ALIGN | 0.5 | 0.6 | 0.1 | 规划器姿态约束 |
| GRASP | 0.1 | 0.2 | 0.0 | 夹爪主导 |
| INSERT | 0.2 | 0.3 | 0.05 | 法向缩幅 0.3–0.5 |
| RELEASE | 0.0 | 0.0 | 0.0 | 只开夹爪 |
| RETREAT | 0.3 | 0.5 | 0.05 | 规划器回撤 |
| WAIT | 0.0 | 0.0 | 0.0 | 保持 |
| RECOVER | 0.0 | 0.0 | 0.0 | 先停 |

### 7.4 监控与回退

| 信号 | 条件 | 动作 |
|---|---|---|
| 进度残差 | 连续 3 块不降 | 重规划；仍不降 → VLA 重查询 |
| 置信度 | `c_t<θ_c` 连续 5 帧 | 回退 VLA chunk |
| 编辑/人手 | `edit_score>θ_e` | WAIT → 重定位 → 重规划 |
| 接触异常 | `r_grasp` 突变 | RECOVER/重抓 |
| 规划失败 | 连续 2 次 `⊥` | 回退 VLA chunk |
| 规划失败 | 连续 3 次 `⊥` | RECOVER |
| 超时 | 单任务 180s 预算 | 安全回撤，结束 |

### 7.5 安全

- 所有动作限幅：位置 ≤1cm/块，旋转 ≤0.05rad/块；
- 规划器路径速度 ≤5cm/s；
- 接触段法向缩幅，切向保留；
- 人手进入工作区 → 零速度保持；
- 任何异常 → 返回上一组合法 chunk 或安全 hold；绝不返回 NaN/错误形状。

## 9. 正确性论证

### 9.1 假设

- **A1（意图可辨识）**：在给定任务/阶段下，阶段边界可由 chunk + 观测以 F1≥0.75 识别；接触边界有迟滞。
- **A2（规划完备）**：RRT-Connect 在 N→∞ 时概率完备；N=300 时失败率 ≤2%（仿真/回放验证）。
- **A3（伺服稳定）**：第 12 轮的离散稳定性条件 `0<KH_c<1`（延迟 1 块）成立；增益按 RTT 降档。
- **A4（教师可用）**：VLA 在 1Hz 内返回合法 30 步 chunk；超时则用缓存 plan。
- **A5（单模型）**：意图头是同一 checkpoint 的附加头；规划/伺服无学习权重。

### 9.2 命题与证明草图

**命题 1（DFA 合法性）**：见 6.5；构造性。

**命题 2（规划可行性）**：见 6.5；构造性。

**命题 3（蒸馏误差）**：DAgger 标准界；需要强凸/无遗憾假设。若不满足，用经验校准 + 置信度门控，不声称理论保证。

**命题 4（分层成功）**：链式法则；独立性假设是保守设计工具。实际中恢复机制会提高成功率，但也会引入新的失败模式。

**命题 5（性能差）**：性能差引理；界相对教师，不是最优。它说明：蒸馏误差 `ε` 会被 `1/(1-γ)` 放大，所以意图头必须校准，不能只看训练准确率。

### 9.3 误差预算的含义

- 若 `p_z=0.98`、`p_p=0.99`、`p_s=0.97`，`K=4` → 78.4%；这要求每一层都非常稳。
- 若意图头只有 95%，`K=4` → 81.5%（规划/伺服完美时）；意图层是最大瓶颈。
- 因此实验门把 G2（意图准确率 ≥95%）和 G4（仿真 +10pp）放在最前；如果 G2 不过，后面的规划/伺服不值得调。

### 9.4 局限

- 命题 4 的独立性假设在现实中不成立（意图错会导致规划器在错误状态规划）；实际成功率可能更低。
- 命题 3 的 DAgger 界需要在线学习器；本报告用监督学习 + 数据聚合，理论保证弱化。
- 规划器依赖占据地图；透明/反光/细线可能漏检，安全保证是概率性的。
- 意图 DFA 是手工/半自动的；32 任务覆盖需要工程，未建模任务用通用 DFA。

### 10.3 2D 玩具验证（D 级，只检查接口逻辑）

**目的**：验证「意图误差按子目标数放大」和「规划器能救回几何不可行的直线」，不预测真机成功率。

**场景**：

- 2D 单位正方形；起点 `(0.1,0.3)`，终点 `(0.9,0.3)`；
- 一个随机圆障碍：`ox∈[0.45,0.55]`、`oy∈[0.10,0.50]`、`r∈[0.08,0.12]`；
- 4 个子目标：`(0.3,y_clear)`、`(0.5,y_clear+0.05)`、`(0.7,y_clear)`、终点；`y_clear=min(0.85,oy+r+0.15)`；
- 基线：直线 VLA chunk（无规划）；
- IPD：意图头 + 网格 A*（60×60，8 邻接）+ 5 步执行 + 目标到达判定；
- 意图误差：每个子目标以概率 `ε` 预测一个「可行但错误」的子目标（离真子目标 >0.25）；机器人到达错误子目标即判失败（模拟错误提交）；
- 每条件 200 次随机场景。

**结果**：

| 方法 | 成功率 | 碰撞率 | 超时率 |
|---|---:|---:|---:|
| VLA 直线 | 44.0% | 56.0% | 0% |
| CHUNK-SERVO 直线 | 44.0% | 56.0% | 0% |
| IPD ε=0 | **100%** | 0% | 0% |
| IPD ε=1% | 96.5% | 0% | 3.5% |
| IPD ε=2% | 94.0% | 0% | 6.0% |
| IPD ε=5% | 83.5% | 0% | 16.5% |
| IPD ε=10% | 62.5% | 0% | 37.5% |
| 理论 `(1-ε)^4` | 100% / 96.1% / 92.2% / 81.5% / 65.6% | — | — |

**读法**：

1. 规划器把「语义对、几何不可行」的直线从 44% 救到 100%；
2. 意图误差按 `(1-ε)^4` 放大：ε=5% → 83.5%，与理论 81.5% 接近；
3. 因此最大风险是意图切换，不是规划器；
4. 玩具的碰撞率为 0 是因为错误意图被建模成「可行但错误」；真实错误可能同时导致碰撞/超时，风险更高。

**复现核心逻辑（伪代码）**：

```python
for trial in range(200):
    obs = random_obstacle()
    subgoals = four_subgoals(obs)
    x = start
    for k, g_true in enumerate(subgoals):
        g_pred = wrong_feasible_goal(obs) if rand()<eps else g_true
        path = astar(x, g_pred, blocked(obs))
        while not reached(x, g_pred):
            x = step_toward(x, path)
            if collides(x, obs): return FAIL_COLLISION
        if not close(g_pred, g_true): return FAIL_WRONG_INTENT
    return SUCCESS
```

- 320 trials 下 `p≈0.25` 的 SE≈2.4pp；不要用 +1–2pp 下结论；
- 配对 A/B 用同初始条件；报告差值 bootstrap 95% CI；
- 仿真每 cell ≥50 次；报告均值 ± 标准误；
- 离线按 session/物体/背景分组划分，相邻帧不跨 split。

## 11. 风险与合规

### 11.1 风险表

| 风险 | 影响 | 缓解 | 证据 |
|---|---|---|---|
| 意图边界错判 | 规划/伺服朝错误子目标 | DFA、置信度、迟滞、多假设、VLA 重查询 | 玩具 ε 扫描 |
| 规划器地图错 | 碰撞/卡住 | 保守膨胀、腕部深度、置信度门控、回退 | G3 |
| 蒸馏分布漂移 | 学生 OOD | DAgger、校准、教师重查询 | G2/G8 |
| VLA/规划器冲突 | 抖动/超调 | `β_z`、限幅、冲突回退 | G4/G8 |
| 单模型解释 | 被判第二模型 | C1/C2/C3；同 checkpoint；确定性控制器 | G9 |
| 延迟 | p99 超标 | 0.5M 头、20ms 规划、1Hz VLA、5 步 chunk | G6 |
| DFA 覆盖不足 | 新任务无阶段 | 通用 DFA + VLA 先验；低置信度回退 | G1 |
| 评测噪声 | 假阳性 | 配对 A/B、bootstrap、重复实验 | G5/G7 |
| 透明/反光/变形 | 规划/伺服失败 | 只对刚体 A 档启用；变形任务回退 VLA | G4/G5 |
| 人手不在视野 | 漏检 | 本体/夹爪/编辑残差兜底 | G4 |

### 11.2 合规三模式

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 意图头只离线生成标签；线上 VLA + 确定性规划/伺服 | 最低 | 保守首选 |
| C2 确定性控制器 | 意图头是同一 checkpoint 附加头；规划/伺服无学习权重 | 低；需说明 | 主推 |
| C3 同 checkpoint 特征 | 意图头用 VLA 同一 encoder 缓存特征；不加载第二模型 | 低–中 | 需要强描述子时 |

**禁止**：加载第二个学习策略/残差网络/独立视觉编码器做在线决策；把规划器训练成神经策略；用 30Hz 广域网跑 6B VLA。

### 11.3 本轮最大风险

**意图头在「对齐→插入」边界错一帧，DFA 和规划器会把错误子目标「合法化」，伺服越准反而越快撞向错误位置；所以 IPD 的成败不在蒸馏精度，而在意图切换的可验证性。**
