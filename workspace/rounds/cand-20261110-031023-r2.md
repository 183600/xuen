# 第 41 轮 · 双灵感落地 v18：多机评测分布 × 指令语义编译（「评测分布」横切层 E-Plane，四层架构 v6）

> 承接第 40 轮（v17：热预算治理 × 步数感知规划 × 学习-TO 混合轨迹，四层架构 v5）。本轮灵感词「多机评测 / 语言指令」。这两个词看起来一个是评测协议、一个是交互模态，和 v17 的「单位物理成本得分效率」不在同一层；但把 v17 的目标函数摊开后会发现，它们戳中的是同一个被隐式默认掉的东西——**v17 的 E_score 是在「一台机器 + 一种说法」上的点估计，而官方评测实际是在「N 台测试机器人 × 一个未公开的指令分布」上抽样**。前者让分数变成随机变量，后者让「任务是什么」本身变成需要接地的假设。**v18 的主轴：把「评测分布」升格为与热/时延/步数并列的横切账本（E-Plane），把「语言指令」从一次性任务标签升格为可编译、可接地、可被物理证据证伪的类型化目标公式；优化目标从单机期望得分改为机器×指令分布上的风险敏感得分。**

## 0. 联网核实（先事实后推理；检索口径 2026-11-10，来源链接见产物区 §5）

- **事实 F67（官方提交仓库 README §5–6，2026-11-10 重新逐行核对）**：评测在 **N 台测试机器人**上以**随机顺序**进行，N 由组委会另行通知；评测端为每台机器人**固定连接一个端口**，提交须从 8765 起暴露**恰好 N 个连续端口**；每个端口对应一台独立机器人的独立 episode，**不同端口可能同时调用**，共享后端须并发且**各端口 reset/历史状态严格隔离**；每步 `get_action` 的**时延与内容均被记录**，时延平滑性 + 动作统计规律性可能随成绩一并展示（与 v17 的 F60 一致，但本轮补充了「N 未公布、端口数须严格等于 N、示例仅给 N=3」三个工程细节）。
- **事实 F68（RoboColosseum，arXiv 2611.02497，2026-11-02）**：分布式真机评测框架，覆盖 SO-101/Franka/Bimanual-YAM/G1 四种本体、124 个站点、5,699 次 Open Track 对比；**不同本体任务套件上的策略排名一致性很弱（Kendall's W=0.24）**，Open Track 排名对微调后排名预测很差且出现大量名次反转；G1 上五个任务没有任何策略完整成功，但平均进度仍有 13.3%–23.2%。**含义：换一台机器/一套硬件，排名可能翻转；单机均值不能代表评测分布。**
- **事实 F69（LIBERO-RIG，arXiv 2610.18843，2026-10-13）**：只扰动机器人硬件与架设、保持任务不变，覆盖 11 条扰动轴（相机安装/光学、相机-机械臂标定、执行增益、控制频率、本体噪声、基座位姿、桌面高度、夹爪垫磨损等）× 5 个严重度 = 210 种条件；**池化成功率从 0.932 降到 0.767（中severity）再到 0.509（最高severity）**，且视觉扰动训练不能缓解「图像不变但硬件变了」的故障。**含义：官方 N 台机器之间的硬件差异本身就足以让成功率减半，多机不是同一台机器的重复采样。**
- **事实 F70（LIBERO-Para，arXiv 2603.28301，2026-03-30）**：仅改写指令、保持场景与动作不变，VLA 在 7 个配置（0.6B–7.5B）上出现 **22–52 个百分点的性能下降**；**80%–96% 的失败来自规划级轨迹分歧而非执行误差**；作者提出 PRIDE 指标量化改写难度。**含义：语言表面形式是独立的分布偏移轴；语言理解错会表现为「执行了一个看似合理但错误的任务」。**
- **事实 F71（MESA，arXiv 2611.05567，2026-11-03）**：语言条件策略的评测框架，提出用**干扰任务完成**来 disentangle「指令接地失败」与「控制执行失败」；最强模型在 MESA 仅 52%、BiMESA 49%；五个 suite 分别隔离空间、实例、类别、组合泛化。**含义：只看成功率会把「拿错物体但动作很成功」误判为执行问题；指令保真度必须单独度量。**
- **事实 F72（IndustrialVLA-Bench，arXiv 2609.25562，2026-09-22）**：在统一协议下比较 6 个 VLA/WAM 系统；**干净 LIBERO 上平均只差 1.58 分，但鲁棒性与改写（paraphrase）分别拉开 14.62 与 31.08 分**；每个分数聚合 3 个随机种子。**含义：真实差距主要藏在鲁棒性/语言改写轴，而不是干净基准均值。**
- **事实 F73（BiDex-100，arXiv 2610.25459，2026-10-18）**：106 个双手灵巧操作任务，五个能力轴（泛化、指令跟随、少示范、长时程、记忆）；指令跟随用**数量变体、组合指令、episode 中途切换指令**三类测试。**含义：语言可以是组合式、对比式、可切换的；官方 UniBot 是指令全 episode 静态（F67），所以「切换」只能作为训练增广，不能假装部署时存在。**
- **事实 F74（DC-Ada，arXiv 2604.03905，2026-04-05）**：异构多机器人团队的部署问题；保持共享策略冻结，只在线适配**每台机器人的紧凑观测变换**，用无梯度、通信极少的 accept/reject 随机搜索，在四种异构度与五个种子上验证。**含义：不做策略微调、只做 per-robot 观测/接口适配，是多机部署的可行轻量路线。**
- **事实 F75（联邦 VLA 实证，arXiv 2609.22973，2026-09-19）**：真实站点之间不只任务不同，**相机位置、光照、背景、机械臂标定与操作者习惯**都不同；两个站点的 `wrist_roll` 分布 Wasserstein 距离达 **101.8°**，直接平均参数会损伤动作精度而非任务接地。**含义：同一型号机器人也会有显著的实例级动作分布偏移，per-port 标定不是过度设计。**
- **事实 F76（CHORUS，arXiv 2606.12352）**：用单一 VLA 主干控制多种机器人，推理时每个机器人只用自己的观测 + **机器人身份 prompt**，无需机器人间通信；真实任务上比从零训练的分散策略高 64 个百分点。**含义：机器身份条件化（machine-conditioned prompting/adapter）是比跨本体预训练更便宜的异构处理方式。**

## 1. 研究者直觉（先直觉与动机，后形式化）

**直觉 1（多机评测 → 分数不是一个数，而是一个分布上的风险泛函）**。v17 把 E_score 写成 `Π p_s · g(N) − λP(fail)`，这本质上是在**我们自己的那台 G1、我们自己的那张桌子、我们自己的那套相机标定**上做点估计。但官方 README 说得很清楚：N 台测试机器人、随机顺序、每台一个固定端口、N 不公布（F67）。F68 告诉我们换本体排名会翻转（W=0.24），F69 告诉我们**只换硬件架设就能让成功率从 0.932 掉到 0.509**，F75 告诉我们同型号机器人的关节分布也能差 101.8°。所以「多机评测」不是「把同一套代码复制 N 份」的工程问题，而是一个统计问题：**我们在优化的是 `S(π; m, ℓ)` 在机器分布 `M` 与指令分布 `L` 上的某个风险泛函，而不是 `S(π; m_0, ℓ_0)`。** 如果只优化均值，我们可能得到一个「在好机器上很高、在坏机器上归零」的策略；官方排名按所有测试机聚合，尾部失败会直接吃掉名次。

**直觉 2（语言指令 → 指令是任务标识，不是输入特征）**。官方语言是单条 `str`、全 episode 不变、无时间轴（F67）。这看起来像「把文本喂给 VLA」这么简单，但 F70 说只改写说法就能掉 22–52 个百分点，且 80–96% 的失败发生在规划级；F72 说干净基准上大家只差 1.58 分，改写轴能差 31.08 分。这说明语言不是可有可无的模态，而是**唯一能区分「拿杯子」和「拿杯子旁边的盒子」的任务标识**。更麻烦的是，F71 指出：策略可能「成功地完成了错误任务」——动作很漂亮，但抓错了对象/关系/数量。只看成功率无法区分「语言接地错」与「执行失败」，而这两者的恢复策略完全相反：前者要重新绑定指称/重解析，后者要重规划/恢复。所以 v18 把语言从「一次性标签」升格为**类型化目标公式 + 指称假设集 + 指令满足度监控**。

**直觉 3（多机 × 语言 → 失败必须归因，恢复才可路由）**。多机让失败来源变多：机器 A 上成功、机器 B 上失败，可能是相机标定、执行增益、桌面高度，也可能是同一句话在 B 上被不同地接地（不同视角导致指称歧义）。如果只有一个「失败」信号，IP-49 只能盲目重规划；但如果我们能把失败拆成 **G-fail（接地错）/ E-fail（执行错）/ U-fail（歧义未消解）**，恢复就能分流：G-fail 回到 IP-53 重新绑定指称，E-fail 回到 IP-38/IP-49 恢复/重规划，U-fail 用主动感知或最小风险计划对冲。这把 v17 的「失败记忆库」从「同一物体×同一技能」升级为「同一指令×同一机器×同一失败类型」。

**直觉 4（E-Plane 与 Δ-Plane 同构：评测分布是第四本账）**。v17 的 Δ-Plane 管热、时延、步数；v18 增加 **E-Plane（Eval-Plane）** 管机器风险 `R_m`、指令不确定性 `U_l`、排名稳定性 `V_rank`、适配预算 `C_adapt`。两者不是并列的第五层，而是互相耦合的横切面：per-port 适配和主动感知要花算力/时延/步数（吃 Δ-Plane），热/时延越紧就越不能做昂贵的指令消歧或机器标定（Δ-Plane 反过来限制 E-Plane）。因此 E-Plane 的决策原则与 IP-48 同构：**只在「风险下降的期望收益 > 物理成本」时才适配/探测**。

**直觉 5（修剪：v17 的跨本体与蒸馏不再是最优兑换）**。规则 51 要求每轮剪。对照官方现实（单一 G1 家族、N 台同型号/近型号测试机、官方已给 VLA 基座），v17 中两项是典型的「能力展示型而非得分型」：(a) **IP-42 CROSS-EMBODIMENT-MOTION**——多机评测是**同本体实例级异构**（标定/相机/增益/桌面），不是跨本体形态迁移；用 per-port 适配器比跨本体预训练便宜一个数量级，而 F76 已经证明机器身份条件化足够。(b) **IP-44 PROGRESSIVE-CURRICULUM-DISTILL**——基座 + LoRA/RARA 已覆盖适配，蒸馏既不解决机器分布也不解决指令接地，数据/算力门槛却最高。本轮把这两项降 P2，兑换给 IP-52/IP-53 两个真正补 v17 短板的 P0。

## 2. 灵感词 → 落地线（新增 + 重构 + 修剪登记）

- 「**多机评测**」→ **IP-52 MACHINE-POPULATION-GOVERNOR（P0 新增）**：把 N 台测试机视为机器分布 `M` 的样本；每端口估计**机器指纹** `φ_m`（相机几何代理、执行增益、控制频率、本体偏差、可达域、时延分布）；用 per-port 轻量观测归一化/动作增益适配（DC-Ada 式，F74）；规划器使用 `p_s(s|σ, φ_m)`；目标从单机均值改为**均值-CVaR 混合 + 方差惩罚**，并诊断 worst-group 与 Kendall 排名稳定性；适配预算受 Δ-Plane 约束。
- 「**语言指令**」→ **IP-53 INSTRUCTION-SEMANTIC-COMPILER（P0 新增，重构 IP-32/升级 IP-30/49）**：把静态指令编译为**类型化目标公式** `ψ=(O,B,R,Q,T,C)`（对象、指称绑定、空间/时间关系、数量、顺序、属性约束）与歧义集；用语义图/观测更新指称后验；用**反事实指令敏感性**（最小指称替换后计划是否变化）训练/诊断；运行时用**指令满足度监控 + 干扰任务探针**区分 G-fail/E-fail；只在价值 of information 为正时做主动感知消歧。
- 升级：**IP-24**（失败监测 → G/E/U 失败归因 + 恢复路由）、**IP-30**（VLM 判别 → 指令满足度/干扰探针）、**IP-32**（并入 IP-53，保留五变体作为数据增广）、**IP-36**（语义图增实例属性/指称绑定/歧义集）、**IP-48**（Δ-Plane 增适配预算 `C_adapt`，per-port 隔离）、**IP-49**（E_score → 风险敏感 + 机器条件化 + 指令后验）、**IP-25**（时延 SLO 增 per-port 方差/排名稳定性）、**IP-21**（旗舰增 machine-conditioned adapter + instruction compiler）、**IP-26**（增广增硬件扰动轴 + 改写轴）、**IP-45**（保留 per-port 最小隔离，不做跨端口 episode 状态共享）。
- 修剪登记：**IP-42 跨本体运动 → P2 挂起**（官方单一 G1 家族；多机是实例级异构，per-port 适配器更便宜；F76 身份条件化足够）；**IP-44 三阶段渐进蒸馏 → P2 挂起**（基座 + LoRA/RARA 已覆盖；蒸馏不解决机器分布/指令接地）；**IP-46 μ 分析维持 P2**（v17 已降）；**IP-47 ⊗ 维持 P2**。
- 新的横切面：**E-Plane（评测分布平面）**——`R_m` 机器风险（CVaR/worst-group）、`U_l` 指令不确定性（指称熵）、`V_rank` 排名稳定性、`C_adapt` 适配预算；与 Δ-Plane 共同调度 IP-52/IP-53，不新增网络层。

## 3. 形式化直觉（严格版见产物区 §3）

**定义 29（评测分布与风险泛函）**：设机器/架设抽样 `m ~ M`、指令抽样 `ℓ ~ L`，单 episode 得分为 `S(π; m, ℓ)`（官方具体合成公式未公开，A42；暂按「成功率 + 步骤分」理解）。定义
`μ(π)=E[S]`、`CVaR_α(π)=E[S | S ≤ Q_α(S)]`、`Var(π)=Var(S)`、`W(π)=min_{g∈G} E[S | m∈g]`。
v18 目标：`J_β(π)=(1−β)μ(π)+β·CVaR_α(π)−λ·Var(π)−c(π)`，β∈[0.1,0.3] 防过度保守；`W` 与 `Kendall's W` 作为诊断而非硬目标。**原则：先保证均值不跌，再用尾部/方差换排名稳定性。**

**定义 30（机器指纹与 per-port 适配）**：`φ_m=(h_cam, g_act, r_ctrl, b_prop, W_reach, L_dist)`：
`h_cam` 为相机-基座几何代理（桌面单应/地平线/相机高度角，借 IP-36 桌面平面）；`g_act` 为执行增益（`median(Δq_obs/Δq_cmd)` 与 EE 位移比）；`r_ctrl` 为控制频率/ chunk 执行墙钟；`b_prop` 为本体偏差（FK(EE) 与上报 EE 位姿之差、夹爪零点）；`W_reach` 为观测到的关节/工作空间边界；`L_dist` 为每步时延分布。适配算子 `õ=N_{φ_m}(o)`、`a_cmd=G_{φ_m}(a_π)`，`N/G` 为小 MLP/仿射，**只依赖官方观测、动作与时序，不依赖额外传感器**；per-port 持久化，但 `reset()` 必须清 episode 历史，指纹缓存需通过平稳性检验（A40）。

**定义 31（指令语义编译）**：类型化目标公式 `ψ=(O,B,R,Q,T,C)`：`O` 对象/类别/实例提及；`B` 指称绑定到语义图实例；`R` 空间/时间关系（左/右/上/下/内/旁/之后）；`Q` 数量；`T` 顺序；`C` 属性/约束（颜色、易碎、重、透明、可压）。编译器 `C(ℓ)={(ψ_i,w_i)}` 输出歧义集；若 `ℓ≡ℓ'` 语义等价，则要求 `C(ℓ)=C(ℓ')`（作为集合）。接地后验 `p(B,ψ|ℓ,o_{0:t})`；指令不确定性 `U_l=H(B|ℓ,o_{0:t})`。**反事实敏感性**：对最小指称替换 `ℓ'`，若 `plan(ℓ)` 与 `plan(ℓ')` 几乎相同，则策略没有使用语言（训练损失/诊断指标）。

**定义 32（风险敏感、指令条件化的期望得分规划）**：
`E_score(π;ℓ,m)=Σ_ψ p(ψ|ℓ,o)·[Π_{s∈π} p_s(s|σ,φ_m)·g(N_π)−λP(fail|ψ,φ_m)]−κU_l`。
`π*=argmax_π J_β(E_score(π;ℓ,M))`；歧义高时对 `ψ∈Amb` 取稳健 `min`。主动感知的价值：`VOI(a_probe)=E_{o'}[max_π E_score|o']−max_π E_score−c(a_probe)`，仅当 `VOI>0` 才探测；`c` 由 Δ-Plane 的步数/热/时延给出。这把「多看一眼睛」变成可计算的决策，而不是默认动作。

**定义 33（失败归因与恢复路由）**：设 `sat(ψ,o_t)` 为目标谓词满足度。
- **G-fail（接地失败）**：`¬sat(ψ,o_t)` 持续，且 `∃ψ'∈Amb\{ψ}: sat(ψ',o_t)`（干扰任务被完成）或指称后验与意图矛盾。
- **E-fail（执行失败）**：`ψ` 已正确接地，但 `sat` 进度停滞/物理失败（滑移、遮挡、不可达）。
- **U-fail（歧义未消解）**：`U_l` 高且无法/不值得探测。
恢复路由 `ρ`：G-fail → IP-53 重绑定/重编译；E-fail → IP-38/IP-49 恢复/重规划；U-fail → 选最小风险计划或探测。**官方指令静态（F67），所以没有「中途换指令」的部署假设；重接地只更新指称，不改变语言输入。**

**定义 34（E-Plane 账本）**：`E-Plane={R_m,U_l,V_rank,C_adapt}`，其中 `R_m` 为机器风险泛函（CVaR/worst-group），`U_l` 为指称熵，`V_rank` 为 bootstrap/机器分层的排名稳定性，`C_adapt` 为 IP-52/IP-53 消耗的算力/时延/热/步数预算。**决策原则**：`C_adapt` 越界→降级适配（先停主动探测，再停 per-port 重标定，最后退回 v17 单机 E_score）；适配不得以超过 Δ-Plane 预算为代价。

## 4. 关键决断

1. **评测分布化**：不再优化单机点估计，改为机器×指令分布上的均值-CVaR-方差泛函；报告 worst-group 与排名稳定性。
2. **机器指纹化**：N 个端口就是 N 个机器样本；用官方观测/动作/时序估计 `φ_m`，做 per-port 轻量适配，不做跨端口 episode 状态共享。
3. **指令编译化**：语言不是标签而是类型化目标公式 + 指称歧义集；用反事实敏感性和指令满足度监控防「成功做错任务」。
4. **失败归因化**：把失败拆成 G/E/U 三类，恢复策略分流；失败记忆库按「指令×机器×失败类型」索引。
5. **修剪两项**：IP-42 跨本体、IP-44 蒸馏降 P2，兑换给 IP-52/IP-53；E-Plane 不新增网络层，只做横切调度。

## 5. 本轮最大风险（一句话）

**N 未公布、机器硬件差异分布未知、官方指令改写分布未知——若机器指纹在单 episode 内不可辨识、且官方指令只是窄模板，那么「多机风险敏感 + 指令语义编译」会退化成两个不可验证的适配器，并因额外计算抬高时延、触碰 F67 §6 的可信度条款；必须以 E73–E78 六重守门，按「指令接地 > 机器适配 > 风险目标」优先序保底，全败即回退 v17 单机期望得分架构。**

### 3.2 IP-52 MACHINE-POPULATION-GOVERNOR（机器分布治理，完整设计）

**IP 卡片（六字段）**：
- **动机**：F67 明示 N 台机器、每端口独立 episode；F68 证明跨机器排名弱一致（W=0.24）；F69 证明只换硬件架设成功率可减半；F75 证明同型号站点动作分布也能差 101.8°。v17 的 E_score 是单机点估计，无法表达「在坏机器上归零」的尾部风险。
- **与现有方案差异**：不是跨本体预训练（IP-42 已降 P2），也不是联邦训练（需要多站点数据与通信）；而是**冻结基座 + 每端口轻量指纹/适配 + 风险敏感聚合**。文献里 DC-Ada（F74）做异构团队观测变换，但未把「评测分布风险」写进规划目标；CHORUS（F76）做身份条件化，但未处理同一本体实例级标定漂移。
- **技术可行性**：`φ_m` 全部可从官方观测/动作/时序估计（无额外传感器）；适配器 <0.5ms；per-port 状态天然隔离（F67）；N 端口可并行估计机器分布。
- **所需资源**：数据=硬件扰动增广（LIBERO-RIG 11 轴，F69）+ 多机标定日志；算力=指纹估计 <1ms/步、适配器 <0.5ms；接口=零改造（只用 `get_action`/`reset`/观测）。
- **落地步骤**：① E73 建机器分布压测；② 实现 `φ_m` 估计器与平稳性检验；③ 实现 per-port 适配器；④ IP-49 接 `p_s(s|σ,φ_m)`；⑤ E-Plane 风险目标上线；⑥ E74 A/B 验收。
- **风险**：单 episode 内指纹不可辨识（→安全微激励 + 冷启动保守）；适配器过拟合（→参数范数约束 + 只调归一化/增益）；端口-机器映射不稳定（→每次 reset 重新估计，不依赖旧缓存）；额外计算抬高时延（→Δ-Plane 硬预算）。

**符号表**：

| 符号 | 含义 | 取值/来源 |
|---|---|---|
| `m ~ M` | 机器/架设抽样 | 官方 N 台测试机（N 未公布，A39） |
| `φ_m` | 机器指纹 | `(h_cam,g_act,r_ctrl,b_prop,W_reach,L_dist)` |
| `N_{φ_m}, G_{φ_m}` | 观测归一化/动作增益适配器 | 小 MLP/仿射，per-port |
| `p_s(s|σ,φ_m)` | 机器条件技能成功率 | 先验表 + 在线更新 |
| `J_β` | 风险敏感目标 | `(1−β)μ+βCVaR_α−λVar−c` |
| `W, V_rank` | worst-group / 排名稳定性 | 诊断指标 |

**算法（per-port 指纹与适配）**：
```
每端口 p 维护：
  φ[p] ← 冷启动先验（由离线硬件增广得到）
  cache[p] ← 可选，仅在平稳性检验通过时复用
reset()：
  ep_state[p].clear()                 # 只清 episode 历史，不动 φ[p]
  ℓ ← obs.language
  ψ_set ← compile(ℓ)                  # 按 ℓ 哈希缓存
每步 get_action(obs)：
  φ[p] ← update_fingerprint(φ[p], obs, last_action)
  if warmup and safe_excitation_allowed:
      a ← small_probe(a)              # 只做小幅、可逆激励
  o~ ← normalize(obs, φ[p])
  plan ← risk_sensitive_plan(ψ_set, φ[p], budget=Δ-Plane)
  a ← gain_correct(policy(o~), φ[p])
  return a
```
**指纹更新（关键量）**：
- `g_act ← EWMA(Δq_obs / Δq_cmd)`，同时算 EE 位移比；`|g_act−1|>ε_g` 触发增益适配。
- `b_prop ← FK(q_joint) − ee_pose_reported`；持续偏差→本体零点校正。
- `h_cam`：用 IP-36 桌面平面 + 地平线估计相机高度/俯仰代理；不追求完整内参，只要能校正归一化。
- `r_ctrl`：chunk 执行墙钟 / 步数；`L_dist`：每步调用时延分布；`W_reach`：观测到的关节/工作空间边界。

**正确性论证**：
- **P51（风险泛函单调性）**：若 `S_1` 一阶随机占优 `S_2`，则 `J_β(S_1)≥J_β(S_2)`（λ=0，β≥0）；方差惩罚项在二阶意义下偏好低方差。故均值-CVaR 目标不会奖励「好机器高、坏机器归零」的策略。
- **P52（指纹可辨识性）**：在 k 步持续激励下，增益估计误差 `O(1/√k)`；无激励时不可辨识——因此冷启动只做低风险归一化，不做过激增益校正（与 A39 一致）。
- **P53（适配安全）**：约束 `‖G_{φ_m}−I‖≤ε_g`、`‖N_{φ_m}−I‖≤ε_n`，适配器只改变输入尺度/动作增益；IP-33 CBF 与 IP-50 MuJoCo 门仍在最低层，任何适配不得绕过。

### 3.3 IP-53 INSTRUCTION-SEMANTIC-COMPILER（指令语义编译，完整设计）

**IP 卡片（六字段）**：
- **动机**：F70 仅改写指令掉 22–52 pp，80–96% 是规划级分歧；F71 证明「成功做错任务」会把接地失败伪装成执行失败；F72 改写轴差距 31.08 分；F73 指令可组合/可对比。官方语言是单条静态 `str`（F67），所以必须在 episode 开始时把它编译成可验证的目标，而不是当黑箱特征。
- **与现有方案差异**：v17 IP-32 只做五个官方变体 + 槽位 + 字符噪声；IP-49 把语言当一个任务标签。v18 把语言编译为**类型化目标公式 + 歧义集 + 指称绑定**，并用**反事实敏感性**与**干扰任务探针**做训练/诊断；恢复时按失败类型分流。
- **技术可行性**：语法/小 LLM 解析 + 语义图绑定，单次 <20ms；指令全 episode 不变，可缓存；无音频/无澄清回合，通道诚实。
- **所需资源**：数据=改写对、指称替换对、干扰任务对（MESA/LIBERO-Para 式）；算力=小 LLM/规则解析；接口=只用 `observation.language` 与观测。
- **落地步骤**：① E75 改写/反事实测试集；② 实现编译器与歧义集；③ 语义图指称绑定；④ 满足度监控/干扰探针；⑤ 接入 IP-24/IP-49；⑥ E76 归因验收。
- **风险**：官方指令可能是窄模板→模块收益低（→E75 门槛 + 降级为规则解析）；LLM 解析错误（→语法/规则优先，LLM 只做兜底）；VLM 满足度噪声（→几何谓词优先 + 弃权）；固定相机下歧义不可消解（→VOI 决策，选最小风险计划）。

**符号表**：`ψ=(O,B,R,Q,T,C)` 类型化目标；`C(ℓ)={(ψ_i,w_i)}` 歧义集；`p(B,ψ|ℓ,o)` 接地点后验；`U_l=H(B|·)` 指称熵；`sat(ψ,o)` 满足度；`ψ'` 干扰/替代目标；`VOI` 探测价值。

**算法（编译—接地—监控—归因）**：
```
compile(ℓ):
  parse → 候选 ψ（对象/关系/数量/顺序/属性）
  对每个 mention：从 IP-36 语义图取候选绑定 B
  返回 {(ψ_i, w_i)}，w_i ∝ parse_score · prior
runtime:
  p(B|ℓ,o) ← 贝叶斯更新（外观/位置/可操作性）
  U_l ← H(B|ℓ,o)
  if U_l > τ_U and VOI(probe) > 0:
      执行小幅主动感知（移动腕相机/微转 pivot），只花 Δ-Plane 允许的预算
  π ← argmax_π Σ_ψ p(ψ|ℓ,o)·[Π p_s(s|σ,φ_m)·g(N)−λP(fail)] − κU_l
  执行 π；每步计算 sat(ψ,o) 与 top-k 替代 ψ' 的 sat(ψ',o)
  if ∃ψ'≠ψ: sat(ψ',o) 且 ¬sat(ψ,o):
      G-fail → 重绑定指称/重编译（不是重试动作）
  elif sat 进度停滞:
      E-fail → IP-38/IP-49 恢复/重规划
  elif U_l 仍高:
      U-fail → 选最小风险计划或继续探测（若 VOI>0）
```
**反事实训练/诊断**：
- `L_para`：语义等价改写对 `(ℓ,ℓ')` 的计划/目标应一致。
- `L_cf`：最小指称替换对 `(ℓ,ℓ')` 的计划应显著不同（若几乎相同，说明策略没在用语言）。
- `L_distract`：场景含干扰物时，若完成的是 ψ' 而非 ψ，记为接地失败（MESA 式）。

**正确性论证**：
- **P54（改写不变性目标）**：若编译器在改写对与反事实对上训练到 `D(C(ℓ),C(ℓ'))≤ε_para`，则语义等价改写下的目标差异有界；E75 直接测该界，不把「不变」当定理。
- **P55（归因可分性）**：若目标谓词可验证且歧义集覆盖真实替代解释，则 G-fail 与 E-fail 在无噪声下可分；VLM 噪声下 Bayes 误差受满足度误判率约束，故监控采用「几何谓词优先 + VLM 弃权」保守策略。
- **P56（探测纪律）**：只在 `VOI>0` 时探测，故在模型正确时探测不降低期望得分；模型错误时用保守阈值 `VOI>δ>0` 与 Δ-Plane 硬预算兜底。

### 3.4 IP-24 升级：失败归因与恢复路由

- **输入**：`sat(ψ,o)`、`sat(ψ',o)`、进度信号（IP-28v2）、证书违约、机器指纹漂移。
- **输出**：`fail_type ∈ {G,E,U}` + 恢复动作 `{re-bind, re-plan, recover, probe, fallback}`。
- **记忆库**：`M_f[(ℓ_hash, φ_m_bucket, fail_type)] → strategy`；同一指令在同一机器桶重复 G-fail → 提升指称先验/换视角；重复 E-fail → 升级技能/换抓取点；重复 U-fail → 降低探测阈值或改最小风险计划。
- **与 v17 差异**：v17 的 `M_f` 是「物体×技能」；v18 改为「指令×机器×类型」，因为多机评测下同一物体在不同机器上可能是不同失败类型。

### 3.6 训练/服务伪代码（v18 增量版）

```python
# ===== 离线：机器分布增广 + 指令改写/反事实数据 =====
def build_v18_data(base_data):
    data_hw = hardware_perturb(base_data, axes=LIBERO_RIG_AXES, severities=5)
    data_para = paraphrase_pairs(base_data)           # 语义等价改写
    data_cf = counterfactual_referent_pairs(base_data) # 最小指称替换
    data_distract = distractor_tasks(base_data, n=3)   # MESA 式干扰
    return data_hw, data_para, data_cf, data_distract

# ===== 离线：训练 per-port 适配器 + 指令编译器 =====
def train_adapters_and_compiler(data_hw, data_para, data_cf):
    phi_encoder = fit_machine_fingerprint(data_hw)     # 从观测/动作/时序
    adapter = train_small_adapter(phi_encoder, data_hw) # 归一化/增益，范数约束
    compiler = train_instruction_compiler(data_para, data_cf)
    return phi_encoder, adapter, compiler

# ===== 运行期：E-Plane + Δ-Plane 联合主循环 =====
def act_v18(obs, port, ep_state, cache):
    # 1. 双平面账本（每步轻量）
    delta = update_delta(H_gpu=telemetry(), H_motor=motor_heat_proxy(ep_state.q_hist),
                         S_used=ep_state.steps, L=ep_state.latency_ewma)
    eplane = update_eplane(port, obs, ep_state)        # R_m/U_l/V_rank/C_adapt
    knobs = governor(delta, eplane)                    # 硬预算：适配/探测/TO 迭代

    # 2. 指令编译（episode 内静态，按 ℓ 缓存）
    if ep_state.psi_set is None:
        ep_state.psi_set = cache.compile(obs.language)

    # 3. 机器指纹与 per-port 适配（reset 只清 ep_state，不清 φ[port]）
    phi = update_fingerprint(cache.phi[port], obs, ep_state.last_action)
    cache.phi[port] = phi
    o_norm = normalize(obs, phi)

    # 4. 指称后验 + VOI 消歧
    ep_state.belief = update_binding(ep_state.belief, obs, ep_state.psi_set)
    if entropy(ep_state.belief) > TAU_U:
        probe = choose_probe(ep_state.psi_set, ep_state.belief, knobs)
        if value_of_information(probe, ep_state) > DELTA_VOI:
            return apply_gain(probe, phi)              # 小幅主动感知

    # 5. 风险敏感规划（机器条件 p_s + 指令后验）
    plan = risk_sensitive_plan(ep_state.psi_set, ep_state.belief, phi,
                               budget=knobs, beta=BETA_RISK)
    # 6. 中层 → TO → 流式执行（继承 v17）
    task = midlevel(plan.waypoints, obs, budget=knobs)
    warm = stream_policy_head(plan.skill, o_norm)
    traj = hybrid_to(task, warm, envelopes=cache.semantic_map.objects,
                     f_track=cache.f_track, weights=(knobs.hot, knobs.precision))
    chunk = (traj or warm).next_chunk(knobs.T_a)
    if not guard.cbf_check(chunk):
        chunk = resample_or_fallback(ep_state, r=2)
    a_cmd = apply_gain(chunk, phi)

    # 7. 满足度监控 + G/E/U 归因 + 恢复路由
    fail_type = attribute_failure(obs, plan, ep_state.belief, cache.semantic_map)
    if fail_type == "G":
        cache.failure_memory.log(obs.language, phi_bucket(phi), "G",
                                 strategy="re-bind/re-compile")
        ep_state.need_recompile = True
    elif fail_type == "E":
        cache.failure_memory.log(obs.language, phi_bucket(phi), "E",
                                 strategy="recover/re-plan")
        ep_state.need_plan = True
    elif fail_type == "U":
        ep_state.need_probe = True

    ep_state.last_action = a_cmd
    ep_state.steps += knobs.T_a
    return a_cmd
```

## 6. 清单迭代规则（继承 27–51 + 本轮新增 52–54）

- 继承规则 27–51（通道诚实/映射验证/SLO/fail-safe/灵感-现实校验/单模型合规/步骤分双解释/稠密监督/方法论遗产/元数据重照亮/语言口径分离/摊销/验证器分级/灵感词落地/层级联合规划/跨本体运动/流式韵律/渐进蒸馏/服务化/证书化/组合代数/热预算/期望得分/学习-TO/修剪优先）。
- **52（新增）：评测分布一等公民原则**——目标必须是机器×指令分布上的风险泛函；报告均值、worst-group、CVaR、方差、排名稳定性；禁止只在单机/单说法上调参。
- **53（新增）：指令语义原则**——语言编译为类型化目标公式 + 指称歧义集；必须区分接地失败/执行失败/歧义未消解；改写/反事实测试是硬门槛；不声称音频、澄清回合或中途换指令。
- **54（新增）：接口诚实适配原则**——per-port 指纹/适配只依赖官方观测、动作与时序；不跨端口共享 episode 状态；`reset()` 清 episode 历史；校准缓存必须 per-port + 平稳性检验，不能成为跨 episode 信息泄漏通道。

**本轮最大风险一句话**：N 未公布、机器硬件差异分布未知、官方指令改写分布未知——若机器指纹在单 episode 内不可辨识、且官方指令只是窄模板，那么「多机风险敏感 + 指令语义编译」会退化成两个不可验证的适配器，并因额外计算抬高时延、触碰 F67 §6 的可信度条款；以 E73–E78 六重守门，按「指令接地 > 机器适配 > 风险目标」优先序保底，全败即回退 v17 单机期望得分架构。

**当前最值得押注**：**IP-52 MACHINE-POPULATION-GOVERNOR**——它把官方「N 台测试机、随机顺序、每机固定端口」从工程负担变成一等优化对象：N 个端口天然提供机器分布的在线样本，而 F68/F69/F75 已经证明机器/架设差异足以让排名翻转或成功率减半。IP-52 的验证路径最短（E73 仿真 + E74 A/B），且即使语言模块失效，per-port 归一化 + 风险目标仍能独立贡献；IP-53 是它的必要搭档，负责保证「在每台机器上都做的是对的任务」。
