# 第 8 轮（灵感循环第 8 轮；本轮灵感：「单模型多任务」×「Gazebo」）

> **基线**：第 7 轮 MetricVoiceGauge-OTL-GC-ER（定义 493–525；引理 73–76；实验 E513–E525）。
> 本轮纪律：**表示共享 + 物理接地校验**。把 v7 分散的多个模型（意图分类、抓取几何、情感评分、风险估计、阈值调节）折叠为**单一多任务骨干**，同时正面承认它带来的**错误相关化**；再用 **Gazebo 数字孪生**对证书做发布前预检，但必须承认：仿真无法消除自身与现实的差距，因此预检只能是「必要条件」而非「充分证明」。

## 0. 直觉与动机

**灵感 1（单模型多任务 → 一个骨干、多个类型化头）**
直觉：v7 的 OTL / GCT / ER 各自带一个小模型，串行推理让端到端延迟叠加，且各模型对同一语音输入的语义理解互相矛盾（例如 NLI 判为「抓取」而情感头判为「抱怨」）。若共享一个编码器 φ，再挂任务条件化的轻量头 h_k，则**同一份感知表示**同时服务意图、抓取、情感、风险与阈值，延迟从「Σ 模块」降为「1 次前向 + 5 个薄头」。但代价是：一个表示错误会让所有头同时出错——**错误从独立变相关**。这不只是工程问题，它直接改变了退化链的概率模型。

**灵感 2（Gazebo → 物理接地的证书预检）**
直觉：证书 C 在真实机器人上验证代价高、且不可反复试错。Gazebo 提供了一个可并行的「物理沙盒」：在发布 C 之前，用摄动物理参数（摩擦、质量、延迟、传感器噪声）跑 K 次 rollout，若违反不变式的比例 ≤ ε，才允许下发。这把「事后诊断」前移为「事前过滤」。但 Gazebo 与被验证系统共享建模假设，若真实失效模式恰好不在仿真分布内，预检会给出**虚假的安全感**。

**两者合起来的核心命题**：单模型多任务让各任务错误相关化，Gazebo 预检又是同分布的，于是「用系统自己的假设去证明系统自己安全」——本轮的主要理论工作就是**把这条循环论证变成可度量的、有界的、可被告警的**。

## 1. 研究问题（轮次升级版）

- **Q1（共享表示的接口同构）**：如何让单一多任务骨干的 K 个头输出与 v7 各模块**同类型、同量纲、同判据**，从而下游 MetricLadder / SoftCert / 退化链**零改动**？
- **Q2（负迁移的可检测与可隔离）**：多任务训练出现任务干扰时，如何在线检测 I_{ij} 超限、并把被污染的头**隔离回退**到 v7 的解析模块，而不是让整条链一起劣化？
- **Q3（Gazebo 预检的统计效力与迁移界限）**：K 次 rollout 的接受判据在多大概率下会放过一个真实失效率超阈的证书？仿真-现实的分布差距如何进入证书置信区间，而不是被忽略？

## 2. 设计原则（在 P7–P9 基础上升级为 P10–P12）

**P10 统一多任务骨架（Unified Multi-Task Gauge Backbone, UMTB）**
```
z = φ(obs, ℓ_voice)                       # 共享编码器
ŷ_k = h_k(z; a_k),  k ∈ K = {intent, grasp, emo, risk, otl}
```
`a_k` 为任务条件化 adapter（瓶颈维度远小于 |z|，保证头轻量）。所有 `ŷ_k` 必须与 v7 对应模块输出**同构**（同一类型签名 + 同一量纲），接口契约由类型检查器强制。

**P11 Gazebo 数字孪生证书预检（Gazebo Certificate Pre-check, GCP）**
对候选证书 C，从先验 `θ_p ~ P_gaz(θ_p)` 采样 K 组物理参数，并行 rollout，记录不变式违反指示：
```
fail_k(C) = 1[ rollout_k(C; θ_p) ⊨ ¬(CVC ∧ SpatialCert ∧ GraspGeo) ]
GCP_accept(C) ⇔ (1/K) Σ_k fail_k(C) ≤ ε_gaz
```
K 与 ε_gaz 由预注册的统计目标 (p_bad, δ_CP) 反解，不凭经验设定。

**P12 任务路由与一致性护栏（Task Router & Consistency Guard, TRCG）**
路由 g(z, conf) 决定每个头当前「被信任 / 被隔离」。隔离判据：①头置信低于 τ_k；②头间一致性约束被破坏（如 intent=grasp 而 grasp 头未激活）；③离线估计的干扰 I_{ij} > δ_int。被隔离的头**单点**回退到 v7 解析模块，未隔离的头继续共享表示。

## 3. 与基线的接口（如何退化）

- UMTB 整体失效（编码器崩溃 / 权重损坏）⇒ 全部头退回 v7 的模块化集成，等价于 MetricVoiceGauge-OTL-GC-ER；
- 单个头失效或被隔离 ⇒ 仅该任务退回 v7 对应模块，其余头不变（**细粒度退化**，比 v7 更平滑）；
- GCP 失效 / 超时 / Gazebo 不可用 ⇒ 跳过预检，改用 v7 的静态证书 + 保守 ε_gaz，等价于 v7；
- GCP 与 UMTB 同时失效 ⇒ 完整退回 v7，不产生 v7 之外的未验证行为。

## 4. 预期贡献

1. **接口同构的多任务折叠**：把 v7 五类类型化信号收敛到单一骨干，给出「头输出偏差 → 证书偏差」的 Lipschitz 传递界（引理 77）；
2. **负迁移的可检测/可隔离机制**：把「多任务一定更好」的隐含假设替换为可证伪的干扰判据（引理 79）；
3. **Gazebo 预检的统计证书**：给出 K 次 rollout 的 PAC 接受界与 sim2real 迁移界（引理 78、79），并显式标注其不可覆盖的共同失效模式；
4. 实验 E526–E540 覆盖：多任务增益/负迁移、预检效力、迁移差距、双重退化等价、50Hz WCET。

## 5. 本轮最大风险

**一句话**：单模型多任务把原本独立的模块错误变成**相关错误**，而 Gazebo 预检又与被验证系统共享建模假设，二者叠加可能让系统「用自己有偏的仿真证明自己有偏的表示是安全的」，形成一种可度量却不会被自动发现的**循环自证**。

## 1. 符号体系增量（定义 526–530）

| 符号 | 含义 |
|---|---|
| `φ: (obs, ℓ_voice) → z ∈ ℝ^d` | UMTB 共享编码器 |
| `K = {intent, grasp, emo, risk, otl}` | 五个类型化任务头索引集 |
| `h_k: z → ŷ_k` | 任务头；输出类型/量纲与 v7 对应模块同构 |
| `a_k` | 任务条件化 adapter（瓶颈宽度 b ≪ d） |
| `I_{ij}` | 任务 j 的共享对任务 i 的干扰（负迁移）量 |
| `δ_int` | 允许的最大干扰阈值 |
| `g(z, conf) ∈ {trust, isolate}^K` | TRCG 路由决策 |
| `θ_p ~ P_gaz(θ_p)` | Gazebo 摄动物理参数（摩擦、质量、延迟、噪声） |
| `fail_k(C)` | 第 k 次 rollout 的不变式违反指示 |
| `ε_gaz, δ_CP` | GCP 的失效率容限与统计置信度 |
| `W₁(P,Q)` | 真实/仿真物理分布的一阶 Wasserstein 距离 |
| `L_V` | 证书评价函数 V(C) 关于状态分布的 Lipschitz 常数 |

**定义 526（统一多任务骨架 UMTB）** 单一骨干 + 多类型化头：
```
UMTB_θ = (φ, {h_k}_{k∈K}, {a_k}_{k∈K})
z = φ(obs, ℓ_voice)
ŷ_k = h_k(a_k(z)),  k ∈ K
接口契约：type(ŷ_k) = type(v7_k) ∧ scale(ŷ_k) = scale(v7_k)
```

**定义 527（任务干扰/负迁移量）** 以单任务模型为参照的期望损失差：
```
I_{ij} = E_{x~D_i}[ ℓ_i(UMTB) − ℓ_i(M_i^single) ]
I_i    = max_{j≠i} I_{ij}          （最坏干扰方向，保守）
接受条件：I_i ≤ δ_int, ∀i ∈ K
```

**定义 528（Gazebo 证书预检 GCP）** 摄动物理参数下的并行 rollout 接受判据：
```
fail_k(C) = 1[ rollout_k(C; θ_p^k) ⊨ ¬(CVC ∧ SpatialCert ∧ GraspGeo) ]
π̂_K = (1/K) Σ_{k=1}^K fail_k(C)
GCP_accept(C) ⇔ π̂_K ≤ ε_gaz
```
其中 θ_p^k ~ P_gaz 独立同分布采样；接受/拒绝还须满足预注册的统计效力（见引理 78）。

**定义 529（仿真-现实证书迁移界 S2R）** 证书评价函数在真实与仿真分布上的差异上界：
```
| V_real(C) − V_gaz(C) | ≤ L_V · W₁(P_real, P_gaz) + η_model
```
η_model 为未建模动力学（接触、柔性、通信延迟）的残差项，由标定实验 E529 估计。若右端超过证书安全裕度，则 C 只能作为「必要条件」通过，需追加低速真实探测。

**定义 530（统一退化标识）** v8 与 v7 的可判定区分：
```
Φ_v8 = { ŷ_k = h_k(φ(·)),  g = TRCG,  C admitted by GCP }
Φ_v7 = { ŷ_k = v7_k(·),    g = ∅,      C admitted by static check }
退化映射 ρ: Φ_v8 → Φ_v7 为逐坐标投影（头失效投影该头，GCP 失效投影第三坐标）
```

## 2. 形式化定义（要点）

**定义 493（MetricLadder）** 保留自 v6/v7；判据向量 τᵢ 可被 OTL 头调节，但**调节量的类型/量纲**由 UMTB 接口契约固定，TRCG 隔离 otl 头时 τᵢ 立即冻结在最后一次可信值。

**定义 494（VoiceCommandTyping）** v8 中 `intent` 头输出与 v6 的 `VoiceCommandTyping` 同构；当 `isolation[intent]=true` 时，调用 v7 的 ASR+NLI 解析路径，而非头部输出。

**定义 495（RewardDecomposer）** 保留自 v7；`risk` 头被隔离时回退 MetaWeight 的解析风险估计。

**定义 496（SoftCert）** v8 中证书 C 发布前多一道 GCP 门：`C_admit = static_check(C) ∧ (GCP_accept(C) ∨ gcp_unavailable)`。

**定义 517/521（OTL）** 保留自 v7；`otl` 头的 θ(t) 与 v7 的移动平均实现同构，便于 A/B 对照。

**定义 528（抓取命令类型化）** 保留自 v7；`grasp` 头直接预测 γ_grasp 所需的几何有效性，但要求输出与 `GraspParser` 同量纲；隔离时回退正则/几何解析器。

**定义 531（逐头信任集）** 在任意时刻，被信任任务集：
```
T(t) = { k ∈ K : conf_k(t) ≥ τ_k ∧ consistent_k(t) ∧ I_k(t) ≤ δ_int }
```
系统只在 T(t) 上使用 UMTB 输出，其余任务使用 v7 模块。

## 3. 关键算法骨架

```python
# IP-351 Unified Multi-Task Backbone：单骨干 + 类型化头
class UnifiedMultiTaskBackbone:
    TASKS = ('intent', 'grasp', 'emo', 'risk', 'otl')

    def __init__(self, encoder, heads, adapters):
        self.φ = encoder                 # 共享编码器
        self.h = heads                   # {k: head_k}
        self.a = adapters                # {k: adapter_k}，瓶颈 b ≪ d

    def forward(self, obs, ell_voice):
        z = self.φ(obs, ell_voice)
        out = {}
        for k in self.TASKS:
            out[k] = self.h[k](self.a[k](z))
        return z, out


# IP-352 Task Router & Consistency Guard：逐头隔离
class TaskRouterConsistencyGuard:
    def __init__(self, tau, delta_int, consistency_rules):
        self.tau = tau                    # {k: 置信门限}
        self.delta_int = delta_int        # 干扰阈值
        self.rules = consistency_rules    # [(predicate over out) -> violated?]
        self.interference = {k: 0.0 for k in UnifiedMultiTaskBackbone.TASKS}

    def route(self, out, conf):
        trust = {}
        for k in out:
            consistent = all(not r(out) for r in self.rules if k in r.scope)
            trust[k] = (conf[k] >= self.tau[k]
                        and consistent
                        and self.interference[k] <= self.delta_int)
        return trust

    def update_interference(self, k, losses_multi, losses_single):
        # 滑动窗口估计 I_k = max_j E[ℓ_k(multi) − ℓ_k(single)]
        deltas = [m - s for m, s in zip(losses_multi, losses_single)]
        self.interference[k] = max(self.interference[k] * 0.9,
                                   0.1 * max(deltas) if deltas else 0.0)


# IP-353 Gazebo Certificate Pre-check：PAC 接受判据
class GazeboCertificatePrecheck:
    def __init__(self, gazebo, eps_gaz, delta_cp, K_max, budget_ms):
        self.gazebo = gazebo
        self.eps = eps_gaz
        self.delta = delta_cp
        self.K_max = K_max
        self.budget_ms = budget_ms

    def required_K(self, p_bad, eps_gaz, delta_cp):
        # 由 Chernoff/Clopper-Pearson 反解：拒绝一个真实失效率 ≥ p_bad 的证书
        # 的漏检概率 ≤ delta_cp（见引理 78，K 为满足式的最小整数）
        import math
        if p_bad <= eps_gaz:
            return self.K_max
        kl = p_bad * math.log(p_bad / eps_gaz) + \
             (1 - p_bad) * math.log((1 - p_bad) / (1 - eps_gaz))
        return min(self.K_max, math.ceil(math.log(1.0 / delta_cp) / kl))

    def precheck(self, certificate, p_bad):
        K = self.required_K(p_bad, self.eps, self.delta)
        fails = 0
        for k in range(K):
            theta_p = self.gazebo.sample_physics()
            if not self.gazebo.rollout_ok(certificate, theta_p):
                fails += 1
                # 早停：即使其余全部通过也无法改变拒绝结论
                if fails > self.eps * K:
                    return False, {'K_run': k + 1, 'fails': fails, 'early_abort': True}
        return (fails / K <= self.eps), {'K_run': K, 'fails': fails}


# IP-350 主闭环（v8）：UMTB 前向 → TRCG 路由 → GCP 预检 → v7 下游
def metricvoicegauge_round_8(M, s, obs, ell_voice=None,
                             umtb=None, router=None, gcp=None):
    # 1. 单骨干前向（延迟：1 次编码 + 5 个薄头）
    if umtb is not None:
        z, out = umtb.forward(obs, ell_voice)
        conf = {k: out[k].confidence for k in out}
    else:
        z, out, conf = None, {}, {}

    # 2. 逐头路由；未信任者回退 v7 模块
    trust = router.route(out, conf) if router is not None else {}
    y = {k: (out[k] if trust.get(k, False) else M.v7_module(k)(obs, ell_voice))
         for k in UnifiedMultiTaskBackbone.TASKS}

    # 3. 用同构信号驱动 v7 下游（MetricLadder / SoftCert / RewardDecomposer）
    tau = y['otl'].thresholds if trust.get('otl', False) else M.metric_ladder.thresholds
    iota, geo_ok = y['intent'], y['grasp'].valid
    w_prime = M.meta_weight(y['risk'].vector, y['emo'].score)

    # 4. 证书生成 → Gazebo 预检门
    C = M.build_certificate(s, iota, tau, geo_ok, w_prime)
    admitted = M.static_check(C)
    gcp_info = {'skipped': True}
    if admitted and gcp is not None:
        admitted, gcp_info = gcp.precheck(C, p_bad=M.p_bad)
    elif admitted:
        admitted = True  # GCP 不可用：退回 v7 静态证书（保守 eps）

    # 5. 共同失效告警：多个头同时被隔离 ⇒ 相关错误信号
    isolated = [k for k, ok in trust.items() if not ok]
    common_mode = len(isolated) >= 2 and (len(isolated) / max(len(trust), 1)) >= 0.4

    return C, admitted, gcp_info, {'trust': trust, 'common_mode': common_mode}
```

## 4. 推导

**引理 77（接口同构的证书偏差传递）** 设各头输出与 v7 模块输出的偏差为 `‖ŷ_k − v7_k‖ ≤ ε_k`，且证书映射 `V(C(·))` 关于拼接信号 `(ŷ_k)_k` 为 L-Lipschitz。则在 TRCG 全信任时：
```
‖V(C_v8) − V(C_v7)‖ ≤ L · ‖(ε_k)_k‖₂
```
证明：证书映射是拼接信号的复合，Lipschitz 定义直接给出。该引理的意义是把「多任务是否安全」转化为**可测量的头偏差预算** `ε_k ≤ V_margin / (L√|K|)`；一旦超预算必须隔离该头。

**引理 78（GCP 的 PAC 接受界）** 设各次 rollout 的 `fail_k` 独立同分布，真实失效率为 p。若 p > ε_gaz，则 K 次采样后平均失效率仍 ≤ ε_gaz 的概率至多
```
Pr[π̂_K ≤ ε_gaz] ≤ exp( −K · KL(ε_gaz ‖ p) )
```
取 `K ≥ ln(1/δ_CP) / KL(ε_gaz ‖ p_bad)` 即可保证「放过真实失效率 ≥ p_bad 的坏证书」的概率 ≤ δ_CP。证明：Chernoff 界（KL 形式）。**该界的全部效力都建立在 i.i.d. 且 P_gaz 覆盖真实失效模式之上**；若失效模式是分布外的，KL 界形式上仍成立，但 p 已不是真实失效率——这正是引理 79 要补的洞。

**引理 79（负迁移的安全隔离）** 若 TRCG 对任务 k 的隔离条件包含 `I_k > δ_int`，且被隔离后任务 k 的信号等于 v7 模块输出，则对任意任务 k，系统实际使用的信号损失不超过 `max(ε_k, I_k) `，且当 `I_k > δ_int` 时损失回到 v7 水平。证明：路由是逐坐标替换，隔离即恒等映射到 v7；未隔离时由引理 77 控制。故多任务不会比 v7「更差而不可见」——最坏情况被显式打上隔离标记。

**引理 80（GCP + S2R 的联合必要条件）** 若 `V_real(C) ≥ V_safe` 而 `V_gaz(C) < V_safe`，则必有
```
L_V · W₁(P_real, P_gaz) + η_model ≥ V_safe − V_gaz(C) > 0
```
即「仿真通过、现实失败」只能在迁移界不为零时发生。证明：由定义 529 的三角不等式直接移项。推论：GCP 的接受只能作为**必要条件**；当迁移界右端 ≥ 安全裕度时，必须追加真实低速探测或降级，不能仅凭 GCP 发布证书。

**引理 81（双重退化正确性）** 若 UMTB 与 GCP 同时不可用，主闭环返回的证书/判据与 MetricVoiceGauge-OTL-GC-ER 逐字段相同。证明：算法骨架中 `umtb=None` 使 `trust={}`，所有 `y[k]` 走 v7 模块；`gcp=None` 使 `admitted=static_check(C)`；其余分支不改变 v7 下游输入，故逐字段等价。**注意**：该引理不覆盖「UMTB 各头同时以相关方式出错且 TRCG 未隔离」的情形——那是本轮显式声明的不安全余量。

## 5. 复杂度分析

| 组件 | 域 | 时间 | 空间 | 正确性锚 |
|---|---|---|---|---|
| UMTB 单次前向 | 在线 | O(|φ| + Σ_k |h_k|)（共享编码只算一次） | O(d + Σ_k b_k) | 定义 526 |
| TRCG 路由 | 在线 | O(|K| · |rules|) | O(|K|) | 定义 531 |
| GCP 预检（K 次并行 rollout） | 发布前 | O(K · T_rollout / 并行度) | O(K) | 定义 528 |
| GCP 早停 | 发布前 | 最坏 O(K)，期望 O(ε_gaz·K / p) | O(1) | 引理 78 |
| v7 下游（MetricLadder/SoftCert） | 主路径 | 不变（WCET ≤ 22ms） | 不变 | 引理 69–76 |
| 端到端主路径（不含 GCP） | 在线 | ≤ 22ms + 头开销 ≤ 3ms | — | 引理 77 |

**预算结论**：GCP 是**发布前**离线/准离线过程，不进入 50Hz 主循环；将其误放进控制周期会直接破坏 v7 的 WCET 保全——这是实现层最容易犯的错误。

## 8. 本轮最大风险

**一句话**：单模型多任务把原本独立的模块错误变成**相关错误**，而 Gazebo 预检又与被验证系统共享建模假设，二者叠加可能让系统「用自己有偏的仿真证明自己有偏的表示是安全的」，形成一种可度量却不会被自动发现的**循环自证**——因此本轮所有「安全性」结论都只能读作**条件性必要条件**，而非充分保证。
