# 第 8 轮 · SPRINT：成功率优先，先审计再融合，把 N 端口变成并行候选

> 检索/复核日期：2026-10-26（UTC）。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮三个灵感词是「UniBot世界挑战赛」「多端口部署」「技术融合」。
>
> 本轮主判断：**UniBot 的胜负手不是再换一个更大的 VLA，而是把排名规则的字典序（成功率 > 步骤分 > 提交日期）翻译成一个「成功判定—重试—恢复」的闭环决策层；先用 SLFA 把失败步分布测出来，再决定预算押终局还是早期；多端口不是运维负担，而是把 K 个终局候选摊薄到 N 个端口的并行测试时算力；技术融合的落点是 VLA 语义 + 立体几何 + 本体接触 + 恢复策略，而不是单一模型能力。**
>
> 这一轮先拆第 7 轮的地基：第 7 轮把「终局独大」当结论，但占位榜的 2 步任务数学反推出终局失败只占 19%–32%，早期失败占 68%–81%。所以本轮第一个实验不是训练，而是审计。

## 0. 本轮先拆地基：六个事实

### 0.1 排名是字典序，不是加权平均

官方手册原文：实时榜单按 32 任务总平均成功率排序；成功率相同按总平均步骤分；仍相同按提交日期早者靠前。每个任务 10 次独立运行，覆盖 5 类泛化各 2 次（位置/干扰物/背景/未见物品/人为干扰）；单次最长 180s，超时记失败；只允许单模型，架构不限；选手自部署，官方只远程调用。

→ 这是一个 **lexicographic objective**：先最大化 \(S\)，再最大化 \(E\)，最后才是日期。任何「提高步骤分但降低成功率」的优化都是负价值。

### 0.2 头部八个模型都不到 30%：强在「会做」，弱在「做完」

占位榜的 8 个名字（MolmoAct2 29.7、WALL-OSS-0.5 28.5、DreamZero 27.9、Spirit-v1.5 25.9、DM0 23.5、π0.5 22.8、GigaBrain-0 22.6、GR00T N1.5 20.5）不是真实提交；数字不可信，但名字对应的公开模型可以作为架构代理：

- **MolmoAct2**：MolmoER + flow-matching action expert，per-layer KV，强空间推理；缺力觉/触觉，G1+Dex1 具身差，终局接触弱。
- **WALL-OSS-0.5**：4B，20+ 具身、1M 轨迹/epoch、gradient-bridged；零样本 task progress 高，但 progress ≠ success，终局精度和恢复弱。
- **DreamZero**：14B WAM（Wan2.1-I2V-14B），7Hz，2× 泛化；N 端口服务成本高，接触动力学可能 hallucinate。
- **Spirit-v1.5**：Qwen3-VL-4B + DiT，RoboChallenge Table30 50.33%；同分布微调强，UniBot 五轴 OOD 未验证。
- **DM0**：embodied-native，spatial CoT，action 梯度不回传 VLM；CoT 延迟、桌面精细操作非强项。
- **π0.5**：开放世界泛化强；精度/接触弱，终局插入/拉链弱。
- **GigaBrain-0**：world-model 生成数据 + RGBD + CoT；合成接触伪影，模型/延迟成本高。
- **GR00T N1.5**：Eagle-2 + DiT 双系统，future latent alignment；VLM 冻结、chunk 长、终局接触弱。

共同瓶颈不是语义理解，而是 **last-mile success decision**：不知道自己做没做完、不会验证、不会重试、不会从人类干扰中恢复；同时 30Hz/180s/N 端口的服务约束把长 chunk 和大模型的延迟问题放大。

### 0.3 占位榜的步骤分是合成常数：终局独大被反证

`leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`，页面仍是 Coming Soon，详情视频是占位。更关键的是数学：

- 对 10 个 2 步任务（50/50 权重），由 \(E = 50P_1 + 50S\)（\(P_1,S\) 为 0–1 小数，\(E\) 为百分数）反推 \(P_1\)，再算 \(p_2 = S/P_1\)。
- 同一模型在 10 个任务上的 \(p_2\) 是同一个常数（MolmoAct2 0.6149、WALL 0.5781、DreamZero 0.5825、Spirit 0.6038、DM0 0.5890、π0.5 0.5937、GigaBrain 0.6209、GR00T 0.5743），标准差 <1e-4。
- 由此得到的终局失败占比只有 19%–32%，早期失败占 68%–81%。

→ 占位榜不是真实失败分布，不能支撑「终局独大」。第 7 轮的终局优先必须降级为待检验假设。真实分布只能靠 SLFA。

### 0.4 接口 v2 有三个被低估的杠杆

`unibot_submission` README：

- **`obs_delta_indices`**：决定传哪些观测 + 每键堆叠几帧；官方示例用 `[-10,-5,-2,0]` 堆 4 帧图像、`[-4,-2,0]` 堆 3 帧本体。→ 接触/速度估计的信号在这里，不用额外传感器。
- **`image_resize`**：每路图像可以单独缩放；示例把高位图降到 240×320、腕部降到 128×128。→ 延迟/带宽/训练-部署一致性的一等变量。
- **`action_chunk_size`**：固定 \(T_a\)，evaluator 执行完整 chunk 才再调用。示例 \(T_a=8\)；公开 LingBot LoRA 用 50 步 chunk（30fps 下 1.67s 开环）。→ 接触任务的长 chunk 是隐形杀手。
- 动作空间是 joint（pivot 7 + 左右臂 14 + 夹爪 2 = 23 维）或 ee；观测有四路 480×640 RGB、双臂关节/EE 位姿、夹爪、lower_body 15、语言。**没有直接深度/力/触觉**；头部的 stereo pair 是我们做几何的入口。

### 0.5 公开生态已经出现「全量数据 LoRA」

`ezhoureal/lingbot-vla-v2-unibot-lora`：LingBot-VLA 2.0（6B 级，公开 LoRA 报 6.3B 总参数；Qwen3-VL-4B + Qwen2 MoE action expert）在 UniBot 全量 32 任务、33,276 集上 LoRA rank 64，10K 步，单卡 RTX 4090，val/loss 0.085，0.35s/50-step chunk；open-loop ArrangePlates MSE 0.229/MAE 0.176。没有公开闭环成功率，但证明「全量数据 LoRA」在消费级卡上可复现。

官方 `UnifoLM-WLA-1.0-Base`（6B，2,500h，64 任务，二指/五指）也开放了冻结 VLM + action expert 的微调代码和 LoRA。

→ 竞争基线已经不是「零样本」，而是「全量数据微调」。差异化必须来自 **成功判定/接触/恢复/服务**，不是「我也微调了」。

### 0.6 多端口 = N 份并行测试时算力

README 明确：N 台测试机器人，N 个连续端口从 8765 起；每端口独立 episode、独立 reset、状态隔离；允许共享模型 + 请求分发；官方记录每步延迟/波动/动作规律性用于可信度。

→ 这不是「起 N 个 server」的运维细节，而是：**N 个端口的请求可以共享一次 VLM 前向/batch（每端口一个编码），把每端口的 K 个终局候选摊薄**；同时延迟必须稳定，不能用动态 K 造成尖峰。这正是 MP-TTS + RAS 的物理基础。

## 1. 主判断：从「更大的 VLA」转向「成功率优先的闭环决策」

### 1.1 失败步未知，先做 SLFA

**SLFA（Step-Level Failure Audit）**：在调试通道上选 6–10 个代表任务（2/3/5 步、放置/插入/拉链/叠放/双手），每个任务 10 次，记录每次的 step score；利用 `score_steps` 的累积权重把 step score 反推到失败步（仅对严格顺序任务唯一）；算：

- 失败步分布 \(f_k\)；
- 到达率 \(R_k\)；
- 终局转化率 \(C = S/R_L\)；
- 早期失败占比 \(E_{\text{early}} = \sum_{k<L} f_k / \sum f_k\)。

决策规则：

- 终局失败 ≥50% → 押 POP/MP-TTS/PCR；
- 早期失败 ≥50% → 押 GAS/PSC（抓取/接近/端口标定）；
- 分散 → 按「期望成功损失」\(R_k(1-p_k)\prod_{j>k}p_j\) 排序，优先最弱步。

这一步把「终局 vs 早期」的争论变成可证伪的实验，而不是继续拍脑袋。

### 1.2 排名规则要求「成功优先」的 Bellman

设 \(V_s(T)\) 为从步骤 \(s\) 出发、剩余 \(T\) 秒的最大成功率；动作 \(a \in \{\text{continue, retry, regrasp, recover, abort}\}\)，耗时 \(d_a\)，当前步成功概率 \(q_a\)：

\[
V_s(T)=\max_a \left[q_a V_{s+1}(T-d_a)+(1-q_a)V_s(T-d_a)\right]
\]

\(V_L=1\)，\(T<0\) 为 0；abort 取 0，其余动作按上式。步骤分价值 \(U_s\) 作为第二目标，只在 \(V\) 相同处比较。这个式子直接给出「什么时候值得重试/恢复」：终局附近 \(V_{s+1}\approx 1\)，一次重试可能救回整条任务；早期重试则要看剩余步骤的到达率。

边际价值：\(\partial S/\partial p_k = S/p_k\)。**最弱的那一步边际价值最高，不一定是终局。** 例如 \(p_1=0.5,p_2=0.6\) → 提升 \(p_1\) 的边际 0.6 > \(p_2\) 的 0.5；\(p_1=0.8,p_2=0.4\) → 提升 \(p_2\) 的边际 0.8 > \(p_1\) 的 0.4。SLFA 测的正是这个。

### 1.3 技术融合的三个层次

- **表示融合**：VLA 语义/语言 + 头部 stereo 的几何（深度/点云/EE 位姿）+ 本体历史（关节/夹爪）。不是把三个大模型拼起来，而是在决策层融合成「成功概率」。
- **数据融合**：官方 33k 成功演示 + 官方 32 任务人类干扰备注 + Dream2Fix 式反事实失败 + 可选实验室数据。成功数据多、失败数据少，必须合成/回放。
- **服务融合**：共享主干 + 每端口状态 + 动态 batching + 固定预算 TTS + 可信延迟。N 端口是算力杠杆，不是负担。

## 2. 方案轮廓：SPRINT

```text
语言(5条复述) ──► SSG-v2 步骤图/谓词 ──► 当前步 s、剩余时间 T
                         │
          ┌──────────────┴──────────────┐
          ▼                             ▼
   SLFA 决定预算分支              PSC 端口标定（stereo→桌面/相机/夹爪）
          │                             │
   ┌──────┴──────┐               ┌──────┴──────┐
   ▼             ▼               ▼             ▼
 早期分支       终局分支         GAS 抓取/接近   PGL/OPT 目标阶梯
 GAS/PSC       POP/PCR/RECAP     │             │
   │             │               └──────┬──────┘
   └─────────────┴──────────────► GPR-VLA（单 checkpoint，T_a=8）
                                       │
                         MP-TTS：K 候选 + POP/DiVeR 选择
                                       │
                         RAS：N 端口 batching / 终局优先 / 稳定延迟
                                       │
                         SVL/RECAP：验证→重试→恢复→再验证
```

- **SPRINT** = Success-Prioritized Retry and Integrated Neural-geometric Test-time selection。
- 组件：
  - **SSG-v2**：32 任务步骤图/谓词/权重；进度跟踪与恢复触发。
  - **SLFA**：失败步审计；决定预算。
  - **GAS/PSC**：早期分支的抓取/接近稳定器 + 端口标定。
  - **PGL/OPT**：终局分支的放置目标阶梯 + 少样本位姿迁移。
  - **POP**：放置结果预测器（立体几何 + 学习校准）；release 前验证。
  - **PCR**：本体接触反射（关节跟踪误差/速度/夹爪 + 盲插策略）；插入/拉链/闭合。
  - **RECAP**：恢复策略（官方备注 + 反事实失败）；同一 checkpoint 的恢复模式。
  - **MP-TTS**：N 端口共享编码 + 每端口 K 候选 + POP/DiVeR 式 verifier；固定延迟预算。
  - **RAS**：排名感知调度（终局优先、chunk 饥饿、deadline、动作规律性）。
  - **GPR-VLA**：WLA-1.0-Base vs LingBot-VLA 2.0 的 bake-off；\(T_a=8\)。
  - **WMD**：可选离线世界模型蒸馏（只做表示，不进运行时）。

一句话：**先用 SLFA 决定打哪一步，再用「判定—重试—恢复」闭环打，最后用 N 端口把候选摊薄。**

## 4. 风险与合规（先立后破）

- **SLFA 可能推翻终局假设**：这是设计目标，不是风险；预算按 SLFA 分支走。
- **调试通道可能不返回 step score**：回退到最终观测/视频谓词 + 成功二值；或先在评分跑里用 step score 做一次性校准。SLFA 的精度会下降，但仍能区分「早期 vs 终局」。
- **公开 LoRA 无闭环成功率**：先复现 + 调试通道 A/B；不把 val/loss 当成功率。
- **6B 模型延迟**：\(T_a=8\)、图像缩放、bf16/FP8、flash attention、TensorRT；必要时换 4B/2.4B 主干或蒸馏；最终仍是一个 checkpoint。
- **N 未知**：按 N=1..8 设计共享后端；端口数必须精确匹配 N；每端口状态隔离；压测 p99。
- **可信度**：固定 K/固定 batch，避免动态尖峰；记录 p50/p95/p99、动作平滑度、异常值。
- **单模型**：POP 是确定性几何评分器；PCR/RECAP 是同一 checkpoint 的模式/头；不调用第二个模型；WMD 只在离线。
- **外部数据/模型**：只用官方数据和许可证明确允许的公开权重；逐项记录 license；实验室数据走合规开关；不碰闭源/爬取数据。
- **人类干扰**：官方备注是剧本；恢复策略要有预算上限（普通任务 ≤2 次，长程 ≤1 次）；超时守卫。

## 5. 一句话押注

**押注：UniBot 的胜负手不是更大的 VLA，而是成功率优先的「判定—重试—恢复」闭环；先用 SLFA 证明失败步，再用 POP/PCR/RECAP 闭环、用 N 端口 MP-TTS 摊薄候选，技术融合落在语义 + 立体几何 + 本体接触三层。**

# 第 8 轮产物区 · SPRINT 技术报告（成功率优先 + 先审计再融合 + 多端口并行候选）

> 目标赛事：宇树科技 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署、官方远程真机 API 评测。检索/复核日期：**2026-10-26（UTC）**。
>
> **结论先行**：公开榜单仍是占位数据；把占位榜的 2 步任务反推后，终局失败只占 19%–32%，早期失败占 68%–81%——「终局独大」没有被证据支持。头部八个模型都不到 30%，共同瓶颈不是语义理解，而是 **last-mile success decision**：不会验证、不会重试、不会恢复，且长 chunk/大模型在 30Hz、180s、N 端口的约束下被放大。本轮方案 **SPRINT** 把排名规则的字典序翻译成「成功判定—重试—恢复」闭环：先用 SLFA 审计失败步，再按分支投入 POP/PCR/RECAP（终局）或 GAS/PSC（早期），用 MP-TTS 把 N 端口变成并行候选算力，用 RAS 保证延迟可信。核心目标不是「更大的 VLA」，而是 **+5pp 成功率**；在 320 episodes、SE≈2.56pp 下，+5pp 约有 91% 概率观测到更高值。

## 1. 事实核对（2026-10-26）

### 1.1 规则：字典序排名

官方手册 [S1][S2]：

- 32 个标准化桌面任务，覆盖抓取、放置、双手协调；只设 **多任务通才模型赛道**，要求单模型完成全部 32 任务；不得混用多个模型；模型架构不限（World Model、VLA 等均可）。
- 每个任务 **10 次独立运行**，覆盖 5 类泛化各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
- 每次运行最长 **180s**，超时记失败；按执行情况计算步骤分。
- 实时榜单按 **32 任务总平均成功率** 排序；成功率相同按 **总平均步骤分**；仍相同按 **提交日期较早** 排序。
- 选手自部署推理服务；官方只远程 API 调用；算力自备；有 **不计分单任务测试通道**，返回该任务的成功率与得分情况。

**含义**：目标函数是 lexicographic，不是加权平均。任何以步骤分为主、成功率为辅的优化都可能排错序。

### 1.2 接口：23 维 joint 动作、可裁剪观测、固定 chunk

- **多端口**：N 台测试机器人；N 个连续端口从 8765 起；端口数必须精确匹配 N；每端口独立 episode、独立 reset、状态隔离；允许共享模型 + 请求分发；不同端口可能同时调用。

### 2.2 六个共同瓶颈

**H1 · Success vs progress 错位。** 多数模型优化 action likelihood 或 task progress；UniBot 的成功是全有或全无（所有步骤完成）。WALL-OSS-0.5 微调后的 60.5% task progress 不等于 60.5% success；π0.5 的长程能力也不等于终局成功。模型缺少「我现在成功了吗」的显式判定。

**H2 · 最后一公里接触。** 插头、网线、拉链、叠碗、拧盖、装盒都需要接触/力/对齐；API 只给 RGB 和本体（关节、EE、夹爪），没有力/触觉。CoPRE 在 Unitree G1 上用无接触运动估计 + 残差做到 82.2% 接触 recall [S21]；Blind Precise Assembly 只用关节位置/速度/动作历史，零样本真机插孔 73% [S22]。这说明本体接触信号可用，但需要显式模块，VLA 的 RGB 端到端不会自动获得。

**H3 · 具身差。** UniBot 是 G1 + Dex1、23 维 joint、四路相机；头部模型的预训练多为 Franka/DROID/YAM/AgiBot。LingBot 2.0 的统一动作空间覆盖 waist/base/hand，是一个较好的适配基础；公开 UniBot LoRA 也证明 23 维映射可行 [S19]。但端口之间的相机/桌面/夹爪差异仍需 PSC。

**H4 · 五轴 OOD。** 位置、干扰物、背景、未见物品、人为干扰各 2 次；干净演示训练出的策略在背景/未见物品/干扰下容易崩。Cracking Mobile Manipulation 显示原子任务 80%、长程组合只有 19%，失败来自执行过程而非局部能力 [S24]；诊断后干预可把长程从 19% 提到 47–49%。UniBot 的 5 步任务（T16/T17）和人为干扰轴正是这个 regime。

**H5 · 延迟/服务。** 30fps、180s、N 端口；公开 LoRA 的 50 步 chunk 在 30fps 下是 **1.67s 开环**；VLA 推理约 0.35s/50-step chunk（4090）。长 chunk 让接触任务无法及时反应；大模型（DreamZero 14B、7Hz）在 N 端口上成本高。Armory 的动作块调度 [S27] 和 Robion 的多机器人 SLA 服务 [S28] 说明：多端口服务是一个调度问题，不是简单复制模型。

**H6 · 没有验证/重试/恢复。** 模型不知道终局是否成功，不会在失败后重抓/重放/重拉；人类干扰后不会恢复。官方 180s 限制和占位榜平均 44s（若真实）说明时间预算还有很大余量，可用于验证/重试/恢复。Dream2Fix 用生成式世界模型合成反事实失败-修正对，120k+ 样本，修正准确率 19.7%→81.3% [S23]；这是恢复策略的直接证据。

### 2.3 为什么「更大的 VLA」不是本轮最优解

- 头部已经是 4B–14B；再大一号的边际收益不确定，但延迟和 N 端口成本确定上升。
- 公开 LoRA 证明 6.3B 全量数据微调可在单卡 4090 完成；真正的差距更可能在「成功判定/接触/恢复/服务」。
- 排名是成功率优先；+5pp 成功率比 +5pp 步骤分更值钱。把算力投入到 POP/MP-TTS/PCR/RECAP 的期望收益高于换 14B 主干。
- 单模型规则允许「一个 checkpoint + 多个内部模式/确定性模块」；不允许「按任务调用多个模型」。我们的设计必须守住这条线。

## 3. 失败分布：SLFA 与占位榜反证

### 3.1 2 步任务的合成常数

对 2 步任务，\(w_1=w_2=50\)。令 \(S,E\in[0,1]\)，则：

\[
E=0.5P_1+0.5S,\qquad P_1=2E-S,\qquad p_2=S/P_1,\qquad \text{terminal share}=\frac{P_1-S}{1-S}
\]

（表中显示为百分数。）

以 MolmoAct2 为例：

| 任务 | \(S\) | 反推 \(P_1\) | \(p_2\) | 早期失败 | 终局失败 | 终局失败占比 |
|---|---:|---:|---:|---:|---:|---:|
| Hang the Cup | 27.3% | 44.4% | 0.6148 | 55.6% | 17.1% | 23.5% |
| Fruit Basket Collection | 27.9% | 45.3% | 0.6149 | 54.7% | 17.4% | 24.2% |
| Pack the Doll | 37.0% | 60.2% | 0.6149 | 39.8% | 23.2% | 36.8% |
| Disconnect Ethernet | 21.3% | 34.6% | 0.6148 | 65.4% | 13.3% | 16.9% |
| Organize Bookshelf | 33.0% | 53.7% | 0.6149 | 46.3% | 20.7% | 30.9% |
| Open Pill Bottle | 28.6% | 46.5% | 0.6148 | 53.5% | 17.9% | 25.1% |
| Zip Up | 33.4% | 54.3% | 0.6150 | 45.7% | 20.9% | 31.4% |
| Store Racket | 28.5% | 46.3% | 0.6149 | 53.7% | 17.8% | 24.9% |
| Conveyor Food Sorting | 32.3% | 52.5% | 0.6149 | 47.5% | 20.2% | 29.8% |
| Remove Pinned Note | 33.8% | 54.9% | 0.6149 | 45.1% | 21.1% | 31.9% |

失败加权终局占比 **27.2%**。同一模型 10 个任务的 \(p_2\) 标准差 <1e-4；8 个模型都是这种结构（表见 1.4）。这更像是「模型级常数 + 任务级首步成功率」的合成器，而不是可解释的真实逐步失败分布。

**因此**：不能从占位榜推出「终局独大」；也不能用它做步骤级归因。第 7 轮的终局优先必须让位于 SLFA。

### 3.2 SLFA 设计

**目标**：估计每个任务的失败步分布 \(f_k\)、到达率 \(R_k\)、终局转化率 \(C=S/R_L\)、早期失败占比 \(E_{\text{early}}\)。

**任务选择**（8 个，覆盖 2/3/5 步与不同终局类型）：

| 任务 | 步数 | 终局类型 | 为什么选 |
|---|---:|---|---|
| T01 HangCup | 2 | 挂杯 | 2 步放置，权重 50/50，映射唯一 |
| T03 PackDoll | 2 | 双手装袋 | 双手 + 放置 |
| T05 DisconnectEthernet | 2 | 拔出 | 反向终局（拔出） |
| T10 PlugCharger | 3 | 插入 | 接触/对齐，权重 30/30/40 |
| T17 OrganizeStationery | 5 | 闭合 | 长程双手，5×20 |
| T19 ZipUp | 2 | 拉链 | 可变形/闭合，50/50 |
| T27 StackBowls | 3 | 叠放 | 堆叠稳定性，30/30/40 |
| T31 OrganizePencilCase | 3 | 拉链闭合 | 闭合终局，30/30/40 |

如果调试槽不足，先做 6 个：T01、T05、T10、T19、T27、T17。

**流程**：

1. 用公开 LingBot UniBot LoRA 或 WLA-1.0 基线部署，跑调试通道；每个任务 10 次；记录每次的 success 和 step score。
2. 对链式任务，step score 唯一映射失败步：2 步 50/50 → 0=第一步失败、50=第二步失败、100=成功；3 步 30/30/40 → 0/30/60/100 分别对应失败在第 1/2/3 步或成功；5 步 20×5 → 0/20/40/60/80/100。**注意**：这只对严格顺序的任务成立；并行/双手任务（T03、T17）需要谓词/视频辅助。
3. 若调试通道不返回 step score：用最终观测 + SSG 谓词 + 腕部视频人工/半自动标注；或选择成功/失败二值，先只估 \(S\) 和 \(R_L\)（到达终局率），用「终局转化率」判断。
4. 统计：bootstrap 95% CI；10 次/任务的 SE 很大（p=0.3 时约 14.5pp），所以**不要用单任务 10 次做成功率的精确 A/B**；SLFA 的用途是失败步分布和分支决策，不是排名。

**决策规则**：

- 终局失败占比 ≥50% → 终局分支：POP + MP-TTS + PCR + RECAP。
- 早期失败占比 ≥50% → 早期分支：GAS + PSC + 抓取/接近数据；POP/PCR 降为辅助。
- 分散（30%–70%）→ 按期望成功损失排序：\(\text{loss}_k=R_k(1-p_k)\prod_{j>k}p_j\)，优先损失最大的步。
- 若 SLFA 因样本不足无法判定：默认做「决策层 + 两端轻量模块」，不做单侧重注。

### 3.3 统计功效与提交策略

- 正式评测 320 episodes；\(p=0.3\) 时 SE=\(\sqrt{0.3\times0.7/320}=2.56\)pp。
- 真实 +3pp：约 79% 概率观测到更高值；+5pp：约 91%。头部 8 个模型在占位榜上相邻名次只差 1–2pp，噪声足以吞掉排名；**不要为 1pp 的榜单波动过度拟合**。
- 调试通道 10 次/任务：单任务 SE≈14.5pp；80 episodes 池化 SE≈5.1pp；仍不足以检测 +3pp。调试通道应用来测**失败步分布/接触/恢复**，不是精确成功率。
- 提交日期是第三 tie-break：如果平台保留多次提交并取最佳，早提交是免费期权；如果只保留最新，早提交只锁定反馈。先读 profile 页确认，再决定「W1 基线提交」还是「W6 首次提交」。

## 4. 成功率优先的控制

### 4.1 字典序目标

\[
\text{maximize } S=\frac{1}{32}\sum_t S_t,\quad \text{then } E=\frac{1}{32}\sum_t E_t,\quad \text{then earlier date}
\]

步骤分只在 \(S\) 相同处比较。不要为了提高步骤分而牺牲成功率；例如「更早释放以拿部分分」可能让成功变成失败，负价值。

### 4.2 边际价值：最弱步骤，不一定是终局

若任务步骤近似链式，\(S=\prod_k p_k\)，则：

\[
\frac{\partial S}{\partial p_k}=\frac{S}{p_k}
\]

- \(p_1=0.5,p_2=0.6\)：\(S=0.30\)；提升 \(p_1\) 的边际 0.60 > 提升 \(p_2\) 的 0.50。
- \(p_1=0.8,p_2=0.4\)：\(S=0.32\)；提升 \(p_2\) 的边际 0.80 > 提升 \(p_1\) 的 0.40。

**结论**：预算应给「最弱且可达」的步骤，而不是固定给终局。SLFA 测 \(p_k\) 和 \(R_k\)；用 \(\text{loss}_k=R_k(1-p_k)\prod_{j>k}p_j\) 排序。

### 4.3 重试/恢复的 Bellman 价值

设 \(V_s(T)\) 为从步骤 \(s\) 出发、剩余 \(T\) 秒的最大成功率；动作 \(a\in\{\text{continue, retry, regrasp, recover, abort}\}\)，耗时 \(d_a\)，当前步成功概率 \(q_a\)：

\[
V_s(T)=\max_a\left[q_aV_{s+1}(T-d_a)+(1-q_a)V_s(T-d_a)\right]
\]

\[
V_L(T)=1,\quad V_s(T)=0\ (T<0)
\]

其中 abort 直接取 0，其余动作按上式。步骤分价值 \(U_s\) 用同一 Bellman 递推，但只在 \(V\) 相同处比较。实际实现：在 180s 上做有限时域 DP，动作集很小；\(q_a\) 由 SSG/POP/PCR 估计；用查表/近似即可。

**直觉**：终局附近 \(V_{s+1}\approx1\)，一次重试可能救回整条任务；早期重试的价值取决于剩余步骤的到达率。若 \(p_1=0.5,p_2=0.6\)，一次早期重试把 \(p_1\) 提到 0.75，\(S\) 从 0.30 到 0.45（+15pp）；一次终局重试把 \(p_2\) 提到 0.84，\(S\) 从 0.30 到 0.42（+12pp）。若 \(p_1=0.8,p_2=0.4\)，早期重试到 0.96 给 \(S=0.384\)（+6.4pp），终局重试到 0.64 给 \(S=0.512\)（+19.2pp）。**没有固定答案，只有 SLFA 估计的 \(p_k\)。**

### 4.4 时间预算与动作块

- 30fps；\(T_a=8\) → 267ms 理想执行；若推理 350ms，有效控制约 2.9Hz，机器人会在 chunk 间等待。
- 180s 足够 ~670 个 8 步 chunk（理想 30Hz）或 ~500 次 350ms 推理；普通任务 1–2 次重试、长程 1 次重试在预算内。
- \(T_a=8\) 是接触反应的最小可行 compromise；50 步 chunk（1.67s 开环）不适合插入/拉链。
- 训练和部署的 `obs_delta_indices`、`image_resize`、\(T_a\) 必须一致；否则模型看到的分布和部署不同。这是公开 LoRA 最容易被忽略的 A/B 点。

## 5. SPRINT 架构

### 5.1 总览

```text
                    ┌────────────────────────────────────────────┐
                    │  共享推理后端（单 checkpoint）               │
                    │  GPR-VLA + POP + PCR + RECAP heads          │
                    └───────────────▲────────────────────────────┘
                                    │  batch / KV cache
        ┌───────────────┬───────────┴───────────┬───────────────┐
        │ PortSession 1 │ PortSession 2        │ PortSession N │
        │ SSG/PSC/历史  │ SSG/PSC/历史          │ SSG/PSC/历史  │
        └───────▲───────┴───────────▲───────────┴───────▲───────┘
                │                   │                   │
           8765 endpoint       8766 endpoint       8765+N-1
                │                   │                   │
             Robot 1             Robot 2             Robot N
```

- N 个轻量 endpoint（websocket），每个端口一个 `PortSession`；共享后端做动态 batching。
- 若 N 较大/显存不足：多副本/多 GPU，但仍是同一 checkpoint 的多副本，不是多个模型。
- `reset()` 只清对应 `PortSession`；全局状态禁止。

### 5.2 SSG-v2：步骤图与谓词

- 输入：`info.json` 的 `score_steps`（步骤名、权重）、5 条复述、任务对象/容器。
- 结构：链式任务用线性图；双手/并行任务（T03、T17）用 DAG；T27 可链式；边表示前置条件。
- 谓词：物体在目标区域、夹爪开/合、容器开/合、拉链状态、堆叠稳定、插头到位。用 RGB + stereo 深度 + EE 位姿 + 夹爪评估；训练时用成功演示和步骤顺序，推理时用轻量视觉/几何检查。
- 用途：进度跟踪、失败检测、恢复触发、时间预算分配、TTS 只在终局步启用。
- 语言：5 条复述全部覆盖；训练时随机采样 + 轻量改写；不要只记一条。

### 5.3 GAS：早期分支的抓取/接近稳定器

若 SLFA 显示早期失败占主导，GAS 是主投资：

- **抓取候选评分**：用 Placeability Metric [S29] 的思想，从 stereo 点云评估候选抓取的稳定性、可达性、碰撞；VLA 提议，几何评分器排序 K 个候选。
- **滑移检测**：夹爪开度 + 腕部图像中物体位移 + 关节跟踪误差；滑移则重抓。
- **接近净空**：stereo 点云 + EE 位姿做路径碰撞检查；选无碰撞的接近方向。
- **端口标定**：PSC 提供桌面/相机/夹爪偏置；GAS 用标定后的几何。
- **数据**：官方成功演示的抓取段 + 位置/背景增强；不需要新模型。

### 5.4 PSC：端口标定

- 头部 stereo pair 估计深度：rectify → SGBM/RAFT-Stereo/轻量深度模型；或用单目深度 + 平面先验。
- 桌面平面：RANSAC 拟合；得到桌面法向/高度。
- 相机外参：结合 G1 正运动学和桌面平面，估计头部/腕部相机相对桌面的位姿。
- 夹爪偏置：episode 开始的开/合动作 + 腕部图像，估计夹爪零点/偏移。
- 端口嵌入：把标定结果编码成小向量，条件化 POP/GAS；不上传、不共享跨端口。
- 风险：stereo 深度噪声；回退到 EE 位姿 + 桌面高度先验 + 单目深度。

### 5.5 PGL/OPT：放置目标阶梯与少样本位姿迁移

- **PGL**：槽位/区域 → 2D 锚点 → 6D 位姿；三级由粗到细；用 SSG 的终局步骤文本和场景几何。
- **OPT**：从官方演示中取 K 条同任务/同阶段的「容器系释放位姿」；算中位数 + 离散度；迁移到当前容器坐标系；离散度大 → 更柔顺/更慢/更多候选；离散度小 → 直接伺服。
- **跨轴**：位姿是相对容器的，不依赖背景/绝对位置；对位置/背景/未见物品轴更稳。
- **输出**：给 POP 的候选分布 + 给 VLA 的目标条件。

### 5.6 POP：放置结果预测器

**目标**：在释放前预测「这个释放位姿会不会成功」，选候选、决定是否重试。

**输入**：立体点云/深度、物体/容器位姿、EE 位姿、夹爪开度、候选释放位姿、VLA 特征（可选）。

**几何特征**：

- 支撑多边形/质心投影的稳定裕度；
- 与容器/其他物体的最小 signed distance（碰撞）；
- 槽位/孔位的对齐误差、净空比；
- 释放高度/自由落体/弹跳风险；
- 抓取-放置兼容性（放置时夹爪是否碰撞）；
- 堆叠/插入的接触面法向匹配。

**评分**：

\[
P(\text{success}\mid x)=\sigma\left(\beta_0+\sum_i\beta_i\phi_i(x)\right)
\]

- 主项是确定性几何分数；学习头只做校准/残差；这样可解释、样本效率高。
- 训练标签：成功演示的正样本 + 反事实失败（Dream2Fix/仿真/规则扰动）的负样本；用 Brier/ECE 校准。
- 推理：对 K 个候选打分，选最高；执行后用 SVL/谓词验证；失败则用次优候选或 RECAP。
- 计算：几何评分 CPU/GPU 并行，毫秒级；不增加大模型调用。

### 5.7 PCR：本体接触反射

**接触检测**（无 force/torque）：

- 用 `obs_delta_indices` 取关节位置历史（如 `[-4,-2,0]`，30fps 下 133ms）；有限差分得速度；用「指令动作 vs 实际位置」的跟踪误差作为接触代理。
- CoPRE 的思路 [S21]：用无接触运动估计期望关节力矩/响应，算残差；G1 上 82.2% recall。我们可以用简化版：PD 跟踪误差 + 速度 + 夹爪开度 → 轻量分类器。
- 夹爪开度异常（物体滑脱/卡住）+ 腕部图像光流作为辅助。

**盲插/闭合策略**：

- 用 Blind Precise Assembly [S22] 的思路，在仿真中训练只依赖关节位置/速度/动作历史的插入/啮合/拧入策略；随机化零件/夹具/抓取/接触；零样本迁移。
- 任务映射：T10/T26 插头/网线、T19/T31 拉链、T09/T28 盒盖/锁扣、T14 拧盖。
- 原语：推、拉、旋转、微摆、退让；由接触签名选择。
- 与 VLA 的分工：VLA 负责接近/粗定位；PCR 负责最后 1–2cm 的接触闭环；触发用 SSG 终局步或接触分数。
- chunk 形状：8 步里前几步接近、后几步小步/保持，减少过冲；每 267ms 一个决策窗口。

### 5.8 RECAP：恢复策略

- **失败检测**：SSG 谓词翻转、PCR 接触异常、腕部图像变化、人类干扰检测（物体被移动/被拿走）。
- **恢复模式**：重抓、重放、重开、重拉、重拧、换手、重新定位物体；同一 checkpoint 的 recovery token/mode。
- **数据**：
  - 官方 32 任务人类干扰备注是免费剧本（例如 T27「把粉色碗向下移动」、T19「拉上拉链之后拉开」、T17「笔盒合上之后手动打开」、T14「拧开盖子之后拧动回来」）。
  - Dream2Fix [S23]：从成功演示生成反事实失败-修正对，120k+ 样本，修正准确率 19.7%→81.3%；结构化过滤（任务有效、视觉一致、运动学安全）。
  - 仿真/规则扰动：物体位移、掉落、滑移、卡滞、夹爪空抓。
- **触发**：只有当 Bellman 价值 > 继续执行的价值时才恢复；普通任务 ≤2 次，长程 ≤1 次；总时间守卫。
- **合规**：恢复是同一 checkpoint 的模式/头，不调用第二个模型。

### 5.9 MP-TTS：多端口测试时选择

- **候选**：每端口在终局步生成 K 个候选（VLA 采样 + OPT 扰动）；非终局步 K=1。
- **共享**：N 个端口共享一次 VLM 前向/batch（每个端口一个编码）；action expert 对 N×K 个序列并行去噪；POP 对 N×K 个候选并行评分。
- **选择**：\(\arg\max_k \hat P(\text{success}\mid x_k)\)；可用 DiVeR [S26] 的 decision-critical verifier 重加权；也可用 POP 的校准分数。
- **执行/回退**：执行最优；失败则次优；超过预算则 RECAP/abort。
- **固定延迟**：为避免可信度尖峰，推荐 **恒定 K**（如 K=4）而不是「终局突然 K=16」；或固定「终局 K=8、其他 K=1」的确定性 schedule，并在模型卡里说明。延迟预算：\(L\approx L_{\text{VLM}}+K L_{\text{expert}}+K L_{\text{POP}}\)；VLM 共享，expert/POP 批处理。
- **与 N 端口的关系**：不是把不同机器人的动作拿来选；而是让 N 个端口的请求共享 batch，把每端口的 K 候选摊薄。N 越大，边际成本越低。
- **证据**：DiVeR 在 LIBERO/RoboCasa/真机 Franka 上验证 verifier-guided TTS；Armory 证明多机器人 action chunk 调度可提升吞吐 18% [S27]；Robion 证明多机器人多模型 SLA 服务可行 [S28]。

### 5.10 RAS：排名感知调度

- **请求分类**：终局步（高 K）、接近步（K=1）、恢复（短 chunk）。
- **优先级**：剩余时间少的端口、chunk 即将耗尽的端口、终局步端口；用 weighted fair queue，避免饿死。
- **批处理**：5–10ms micro-batch window；最大 batch；固定 K；避免动态 shape 导致的延迟尖峰。
- **动作块调度**：Armory [S27] 的洞察——不同机器人消耗 chunk 的速率不同，naive batching 会错配；按 chunk 消耗/剩余动作调度。
- **双流**：Robion [S28] 的 VLM/ADiT 双流 + 动态 SM 限制；在我们的单模型上可做 VLM prefill 与 action expert 去噪的 overlap。
- **KV cache**：每端口缓存当前观测的 VLM 编码；K 候选共享；历史 KV 按端口隔离。
- **可信度**：记录 p50/p95/p99、动作平滑度、异常值；固定 schedule；warmup；CUDA graphs；超时回退到上一个安全 chunk。
- **压测**：N=1..8，30min，随机延迟/丢包；目标 p99 < 500ms（或实测可行值）；无跨端口状态污染。

### 5.11 GPR-VLA 主干与 WMD

**主干 bake-off**：

- **A：UnifoLM-WLA-1.0-Base**（官方，6B，2,500h，64 任务，G1 原生，冻结 VLM + action expert 微调/LoRA）。
- **B：LingBot-VLA 2.0**（6B 级/6.3B，60k h，20 种构型，55 维动作空间，公开 UniBot LoRA，Apache-2.0）。
- 同一数据、同一 \(T_a=8\)、同一 `obs_delta_indices`/`image_resize`；在调试通道上选。
- 动作空间：23 维 joint（pivot 7 + arms 14 + grippers 2）；LingBot 的 canonical 55 维取对应 23 维，其余置零/忽略；确保归一化一致。

**\(T_a=8\)**：30fps 下 267ms；与官方示例一致；接触可控。训练时用 8 步 chunk；不要用 50 步训练再部署 8 步（分布不匹配）。若必须复用 50 步 LoRA，先做 8 步 prefix 微调/掩码训练。

**WMD（可选）**：用冻结世界模型提取训练帧特征，蒸馏进 VLA 的表示（Think Like a World Model [S25]：0.8B 学生，LIBERO 97.9%、RoboCasa-GR1 50.5%、32ms/1.86GB RTX5090）。只做离线表示学习；不加载世界模型进运行时；不增加推理成本。

### 5.12 合规：一个 checkpoint

- POP：确定性几何评分器（可含一个小的校准头，但在同一 checkpoint/同一服务内）。
- PCR/RECAP：同一 checkpoint 的模式/头；不是第二个模型。
- GAS/PSC：确定性几何 + 同一 checkpoint 的抓取头。
- 不按任务调用不同模型；不把多个模型的输出 ensembling 成最终策略（除非规则明确允许）。
- 若使用 WMD，只离线蒸馏；最终提交是一个模型。
- 模型卡写清楚：单 checkpoint、内部模块、无外部模型调用。

## 6. 伪代码

### 6.1 端口会话与服务

```python
class PortSession:
    def __init__(self, port, token):
        self.port = port
        self.token = token
        self.ssg = SSGv2()
        self.history = []
        self.calib = None
        self.failure = None

    def reset(self):
        self.ssg.reset()
        self.history.clear()
        self.calib = None
        self.failure = None

class SprintServer:
    def __init__(self, policy, n_ports):
        self.policy = policy
        self.sessions = {p: PortSession(p, TOKEN) for p in range(8765, 8765 + n_ports)}
        self.scheduler = RAS(policy)

    async def handle(self, port, obs):
        s = self.sessions[port]
        if obs.is_first:
            s.calib = self.policy.calibrate(obs)
        s.ssg.update(obs, s.calib)
        req = Request(port, obs, s, self.policy.decide_mode(s))
        return await self.scheduler.submit(req)
```

### 6.2 `get_action`

```python
def get_action(self, obs, session):
    step = session.ssg.current_step
    mode = self.decide_mode(session)

    if mode == "recovery":
        chunk = self.model.recover(obs, session.failure, session.calib)
    elif mode == "terminal":
        cands = self.model.sample(obs, k=K_TERMINAL, calib=session.calib)
        cands = self.opt.augment(cands, session.ssg, session.calib)
        scores = self.pop.score(cands, obs, session.calib)
        chunk = cands[int(scores.argmax())]
    else:
        chunk = self.model.act(obs, calib=session.calib)

    chunk = self.pcr.shape(chunk, obs, session)
    return self.pack(chunk, session.token)
```

### 6.3 终局选择与恢复

```python
def terminal_step(self, obs, session):
    cands = self.model.sample(obs, k=K_TERMINAL)
    cands = self.opt.augment(cands, session.ssg, session.calib)
    scores = self.pop.score(cands, obs, session.calib)
    order = scores.argsort(descending=True)

    for idx in order:
        chunk = cands[idx]
        yield chunk
        if self.ssg.verify(obs_after(chunk)):
            return "success"
        if self.time_left(session) < self.min_time_for_next(order):
            break

    session.failure = self.diagnose(obs, session)
    return "recover"
```

## 7. 数据引擎

### 7.1 官方 33k 成功演示

- 32 任务、约 33k 集、30fps、四路相机、5 条复述。
- 用 `score_steps` 的步骤名 + 视频/物体运动/夹爪状态切段；每段 1–2s；得到「抓取段/接近段/终局段/闭合段」。
- 每段带任务 ID、步骤 ID、语言复述、EE 位姿、夹爪、相机帧。
- 用途：行为克隆、SSG 谓词训练、PGL/OPT 的位姿统计、POP 的正样本。

### 7.2 反事实失败合成

- Dream2Fix [S23]：从成功演示扰动动作，生成 photorealistic 失败 rollout；结构化过滤（任务有效、视觉一致、运动学安全）；120k+ 对；修正准确率 19.7%→81.3%。
- 我们的范围：只对 8–12 个 SLFA 任务生成；扰动维度：释放位姿（平移/旋转/高度）、抓取偏移、插入角度、拉链速度、物体初始位置。
- 标签：成功/失败 + 失败步 + 修正动作；用于 POP 校准、RECAP 训练、PCR 接触分类器。
- 合规：生成数据只用于训练；最终一个 checkpoint；不把世界模型带进运行时。

### 7.3 官方人类备注

32 任务的 `generalization` 字段给出 `human_1_note`/`human_4_note`（第 7 轮 [S9]）。例如：

| 任务 | 人类干扰剧本 | 恢复目标 |
|---|---|---|
| T27 StackBowls | 叠了第二个之后拿下第二个 | 重新放置 bowl2 → 继续 bowl3 |
| T19 ZipUp | 拉上拉链之后拉开 | 重新拉合 |
| T17 OrganizeStationery | 笔盒合上之后手动打开 | 重新合上（终局步） |
| T14 PourOutMedicine | 拧开盖子之后拧动回来 | 重新拧开 → 倒药 |
| T10 PlugCharger | 抓插头前进行移动；将插头拔起 | 重新抓取 → 插入 |

这些备注是「免费的对抗剧本」：在仿真/实验室脚本化回放，生成 recovery 对；比自造干扰更贴近评测。

### 7.4 实验室数据（可选）

- 1–2 个任务、100–200 集、不同桌面/光照/背景/布局；用 G1 遥操作采集。
- 只补背景/位置轴的多样性；不碰未见物品/人为干扰（官方数据 + 合成更可控）。
- 合规开关：默认关闭；确认规则允许后并入；保留数据协议/许可/贡献者。

### 7.5 数据平衡

- 成功演示多、失败少 → 反事实合成 + 人类备注回放 + 硬负例挖掘（POP 误判、PCR 漏检、RECAP 误触发）。
- 步骤级标签不平衡 → 按步骤/任务重采样；终局段过采样（但不要牺牲早期段）。
- 语言 5 条复述 → 每任务均衡采样；避免模型只记一条。

## 8. 训练配方

### 8.1 主干 bake-off

| 项 | A：WLA-1.0-Base | B：LingBot-VLA 2.0 |
|---|---|---|
| 参数 | 6B | 6B 级/6.3B（Qwen3-VL-4B + Qwen2 MoE expert） |
| 预训练 | 2,500h、64 任务、G1 原生 | 60k h、20 种构型、55 维动作 |
| 微调 | 冻结 VLM + action expert / LoRA | LoRA rank 64（公开 UniBot LoRA 可复现） |
| 硬件 | 1–2×A100/H100 | 单卡 4090 可 LoRA；A100 更快 |
| 风险 | 官方数据/任务匹配好，但社区基线少 | 公开 LoRA 无闭环成功率；需自测 |

**决策**：同一数据/同一 \(T_a=8\)/同一观测配置，跑 10K 步 LoRA；在调试通道的 6 个 SLFA 任务上比失败步分布和终局转化率；选一个做主线，另一个做备份。

### 8.2 动作块与观测

- \(T_a=8\)；30fps；8 步 = 267ms。
- `obs_delta_indices`：图像 `[-10,-5,-2,0]`（可选，视显存/延迟）；关节/EE/夹爪/lower_body `[-4,-2,0]`；语言 `[0]`。
- `image_resize`：高位 240×320 给 VLA；PSC 的深度可用同一对 240×320 stereo，或额外保留 480×640（会增加延迟）；腕部 160×160 或 128×128；训练/部署一致。
- 动作：23 维 joint；meanstd 归一化；pivot/arms/grippers 分别归一化。
- 训练时随机丢弃相机/帧，提升对传输/延迟的鲁棒性。

### 8.3 损失

\[
\mathcal{L}=\mathcal{L}_{\text{FM}}+\lambda_1\mathcal{L}_{\text{step}}+\lambda_2\mathcal{L}_{\text{pop}}+\lambda_3\mathcal{L}_{\text{recap}}+\lambda_4\mathcal{L}_{\text{lang}}
\]

- \(\mathcal{L}_{\text{FM}}\)：flow matching 动作损失。
- \(\mathcal{L}_{\text{step}}\)：SSG 步骤谓词的 BCE/辅助分类（进度）。
- \(\mathcal{L}_{\text{pop}}\)：POP 成功概率的 Brier/BCE；校准。
- \(\mathcal{L}_{\text{recap}}\)：恢复动作的 BC/flow matching；只在失败样本上。
- \(\mathcal{L}_{\text{lang}}\)：5 条复述/改写的一致性（可选）。

### 8.4 课程

1. **BC**：官方 33k 成功演示；\(T_a=8\)；基础动作。
2. **Step**：SSG 谓词/进度辅助；POP 正样本。
3. **Failure**：Dream2Fix/规则扰动/人类备注；POP 校准 + RECAP。
4. **Port**：PSC 标定 + 相机/图像缩放/延迟增强；多端口模拟。
5. **TTS**：K 候选 + POP 选择；固定延迟；校准。

### 8.5 算力

- 微调：1–2×A100/H100（LoRA 可单卡 4090，但 10K 步耗时较长）。
- 推理：1×H100/L40S 可服务 N=1–8 的共享后端（视延迟目标）；若 N 大/延迟紧，多 GPU 多副本。
- 存储：33k 集视频约数 TB；训练时按需解码/缓存；33k 集的视频解码是主要 I/O 瓶颈。

## 9. 多端口服务

### 9.1 拓扑

- N 个 websocket endpoint，端口 `8765..8765+N-1`；每个 endpoint 只做协议/序列化/转发。
- 共享后端：请求队列 → micro-batcher → 模型前向 → 结果分发。
- 若单 GPU 显存/延迟不够：多副本/多 GPU；每副本仍是同一 checkpoint；端口到副本的映射固定或动态。
- 端口数必须精确匹配 N；用 `N_PORTS` 环境变量启动；不要多开/少开。

### 9.2 状态隔离

- `PortSession` 持有 SSG、历史、标定、失败状态、KV cache、action queue。
- `reset()` 只清当前端口；禁止全局 `self.state`。
- 不同端口的任务/机器人/阶段可能不同；不要假设同步。
- 日志带 port_id；便于排查跨端口污染。

### 9.3 动态 batching

- 5–10ms micro-batch window；最大 batch；固定 shape/填充。
- 终局 K 候选与普通请求分开 batch；或统一 K=4，避免动态 shape。
- VLM 编码按端口缓存；K 候选共享。
- action expert 去噪 N×K 并行；POP 评分并行。
- 超时/掉队请求：回退到安全 chunk 或上一个动作；不要阻塞整个 batch。

### 9.4 延迟与可信度

- 目标：p99 < 500ms（或实测可行值）；p50/p95 稳定。
- 避免动态 K、动态分辨率、动态 batch 导致的尖峰；固定 schedule + 预热。
- 动作良构：限幅、限速、jerk 限制；不要返回 NaN/Inf/异常值。
- 记录：每步延迟、batch size、K、端口、阶段；发布时附 p50/p95/p99。
- 可信度不是「越快越好」，而是「稳定 + 良构 + 与任务阶段匹配」。

### 9.5 压测

- N=1..8；30min；随机请求间隔/延迟/丢包；模拟终局 K 尖峰。
- 指标：p50/p95/p99、吞吐、GPU 利用率、显存、跨端口状态错误、动作异常率。
- 通过标准：无跨端口污染；p99 在目标内；动作无异常；恢复后能继续。

## 10. 评测协议

### 10.1 阶段 0：SLFA（W1）

- 6–8 任务 × 10 次；调试通道；step score → 失败步。
- 输出：失败步分布、到达率、终局转化率、早期/终局分支决策。
- Go/No-Go：若无法区分分支，默认「决策层 + 两端轻量模块」。

### 10.2 阶段 1：离线（W2–W3）

- held-out 2% 官方数据：动作 MSE/MAE、步骤谓词准确率、POP AUC/Brier/ECE、PCR 接触 recall/precision、RECAP 恢复成功率。
- 反事实失败集：POP 排序准确率、Top-1 选择增益、误判率。
- 延迟：单请求/批量/K 候选的 p50/p95/p99。

### 10.3 阶段 2：调试通道 A/B（W4–W5）

- 2–3 个任务（T10/T19/T27）；baseline vs +POP/MP-TTS；+PCR/RECAP。
- 每个配置 10 次；配对比较；看失败步分布/终局转化率，不只看成功率。
- 通过标准：终局转化率 +10pp（或失败步前移）；无早期回归。

### 10.4 阶段 3：正式评分（W6–W7）

- 32 任务 × 10 次；提交 1–2 次；记录每任务成功率/步骤分/延迟。
- 统计：320 episodes，SE≈2.56pp；+5pp 目标；不要为 1pp 波动改方案。
- 若平台保留多次提交：早提交基线锁定日期；后续取最佳。若只保留最新：W6 首次、W7 最终。

### 10.5 阶段 4：冻结（W8）

- 合规检查：单 checkpoint、无外部模型、token、端口数、状态隔离、延迟。
- 模型卡：组件、数据、限制、可信度指标。
- 最终提交 + 备份。

### 10.6 成功指标

- 主指标：32 任务平均成功率；目标 +5pp（相对基线）。
- 次指标：平均步骤分；目标不降。
- 过程指标：终局转化率、早期失败率、POP 校准、PCR recall、RECAP 恢复率、p99 延迟。
- 统计：+3pp 约 79%、+5pp 约 91% 概率观测到更高值；不保证排名，但方向可测。

## 12. 风险与合规

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| SLFA 推翻终局假设 | 中高 | 高 | 设计上接受；按分支走 GAS/PSC |
| 调试通道不返回 step score | 中 | 中 | 视频/谓词/成功二值回退；选链式任务 |
| 公开 LoRA 闭环差 | 中 | 高 | 先调试 A/B；WLA-1.0 备份；不把 val/loss 当成功率 |
| 6B 延迟过高 | 中高 | 高 | \(T_a=8\)、缩放、FP8、TensorRT；换 4B/2.4B |
| N 未知/端口不匹配 | 中 | 高 | `N_PORTS` 精确启动；压测 N=1..8 |
| 可信度尖峰 | 中 | 中 | 固定 K/batch；预热；p99 监控 |
| 多模型违规 | 低 | 高 | 单 checkpoint；确定性模块；模型卡 |
| 外部数据违规 | 低 | 高 | 只用官方 + 许可证允许的公开权重；实验室数据合规开关 |
| 人类干扰恢复失败 | 中 | 中 | 官方备注剧本；恢复预算；超时守卫 |
| 立体深度噪声 | 中高 | 中 | 单目/EE/桌面先验回退；PSC 校准 |
| 动作块固定太短 | 中 | 中 | 训练/部署一致；chunk 内减速/保持 |
| 过拟合调试任务 | 中 | 中 | 任务分层；正式跑前不针对单任务调参 |

**合规底线**：

- 一个提交模型；不按任务调用不同模型；不把多模型输出 ensembling 成最终策略。
- POP 是确定性几何 + 同一 checkpoint 的校准头；PCR/RECAP 是同一 checkpoint 的模式。
- WMD 只离线；最终提交不加载世界模型。
- 只用官方数据和许可证明确允许的公开权重；逐项记录 license；实验室数据走合规开关。
- 不伪造延迟/动作；不返回异常值；不绕过 token/端口/状态隔离。

## 15. 开放问题

1. **N 是多少？** 官方另行通知；按 N=1..8 设计，端口数必须精确匹配。
2. **调试通道每次返回几次运行？是否返回 step score？** 若返回，SLFA 可直接用；若不返回，需视频/谓词回退。
3. **是否保留多次提交？取最佳还是最新？** 决定早提交策略和 tie-break 价值。
4. **外部数据/预训练权重边界？** 官方数据 + 许可证允许的公开权重是否足够；实验室数据是否允许。
5. **动作块是否必须固定？** README 说 `action_chunk_size` 固定；确认 evaluator 是否接受变长（预计不接受）。
6. **延迟上限/可信度阈值？** 只写「稳定」，没有硬指标；用 p99<500ms 作为内部目标。
7. **成功谓词细节？** 32 任务的官方判定条件；用 `score_steps` + 调试反馈校准。
8. **人类干扰的时机/幅度？** 备注给了剧本；具体触发时刻/位移未知。
9. **物体模型/CAD 是否提供？** 影响 POP 的质心/支撑多边形；没有则用多视图/形状先验。
10. **立体深度质量？** 头部 stereo 的基线/标定；若太差，用单目/EE/桌面先验。
11. **是否允许测试时多次采样/verifier？** 规则未禁止；单模型内 TTS 应允许；避免多模型。
12. **单模型如何界定？** 一个 checkpoint + 内部模块/确定性代码；不调用第二个模型。模型卡写清楚。

## 16. 一句话押注

**押注：UniBot 的胜负手不是更大的 VLA，而是成功率优先的「判定—重试—恢复」闭环；先用 SLFA 证明失败步，再用 POP/PCR/RECAP 闭环、用 N 端口 MP-TTS 摊薄候选，技术融合落在语义 + 立体几何 + 本体接触三层。**
