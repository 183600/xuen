# 第 43 轮（新循环第 1 轮） · 策略感知的任务分解：把「证书」升格为「可竞标的技能契约」（四层架构 v8）

> 承接第 42 轮 v19（SCV × CKB × ECR 的 Sim-Cert-RAG 飞轮）。v19 已经把「证书怎么持续进化、怎么低成本上边缘」解决得相当好，但它仍把比赛当成**一个需要被安全完成的任务**，忽略了 UniBot 是**有对手、有比分、有时间窗的比赛**。本轮两个灵感词正好补上这两块缺失：**任务分解**把证书从「整机一张大证书」拆成「带前后条件的技能契约树」——长时程任务的安全性由子契约的链式组合推出，合成粒度、复用粒度、验证粒度同时下降；**比赛策略**第一次让系统显式地在「安全预算」与「比分收益」之间做在线权衡——把安全边际看成一种会在比赛里被花光的资源，策略层根据比分差、剩余时间、对手行为决定「任务拆多细、留多少余量、冒多大险」。两者在同一个对象上汇合：**技能契约既是任务分解的节点，也是策略层竞价的标的**；所谓选出比赛策略，本质是在契约组合空间里做一次带风险约束的最优投标。

## 0. 直觉与动机

**灵感 1（任务分解 → 证书的「乐高化」）**：v19 的证书是「一整块」——一个技能一条自动机、一个不变式、一套阈值。直觉上它像浇筑好的整块混凝土：能承重，但改动一点就要重浇。任务分解提供的是「乐高化」：把「抓取放置」拆成 `导航到台前 → 预抓取对齐 → 闭合夹爪 → 抬升 → 转运 → 对位释放`，每个子技能自带 `(pre, post, invariant, 安全契约)`。关键的性质不是「拆得越细越好」，而是**组合可证**：只要每个子契约在其 `pre` 上 sound，且相邻接口 `post_i ⇒ pre_{i+1}` 被接口证覆盖，父任务就自动 sound。这把 v19 里「整机 CEGAR/仿真压力测试」的 O(|X|) 成本，降成「子技能验证 + 接口验证」的 O(Σ|X_i| + |接口|)，而且大量子契约可以直接从 CKB（IP-55）检索复用。更深一层：分解粒度本身是个可优化变量——粗粒度接口少但单点证书难证，细粒度局部易证但接口爆炸，存在一个由「验证成本 + 接口失配风险」共同决定的最优深度 d*。

**灵感 2（比赛策略 → 安全预算的「经济学」）**：v19 的所有阈值都假设「安全越多越好」，这在比赛里是错的。比赛有比分、有倒计时、有对手：领先时应保守保分，落后时必须激进抢分；对手强时该压缩风险敞口，对手失误时该加码。直觉上，安全边际像**预算**而不是**常量**：一场比赛允许的总体违规概率 δ_match 是有限的，每个技能执行都要「花掉」一点；策略层的职责就是在「预期得分」和「预算消耗」之间做分配。于是「比赛策略」不再是外挂的启发式，而是一个**带机会约束的 POMDP**：状态含比分差、剩余时间、对手信念、机器人健康度，动作是「选哪套任务分解 + 给每个子契约分配多少安全预算 + 是否加速/降级」，目标是 `max E[Score] s.t. P(unsafe) ≤ δ_match`。这样 v19 的 `α_e·θ_sim`、LCS 的 anytime 档位、ECR 的查表降级，全都变成策略层可调度的**动作原语**。

**灵感 3（两者的化学反应 → 契约市场与元策略）**：真正有意思的是二者不是加法而是乘法。任务分解产生了**多个可行计划**（同一任务可有激进分解与保守分解）；比赛策略则需要在这些计划间**竞标**。于是一个自然的机制浮现：每个候选子契约向策略层「报价」——`(预期收益, 安全预算消耗, 时间消耗, 置信度)`；策略层在 `Σ预算 ≤ δ_match` 与 `Σ时间 ≤ T_left` 两个约束下做带风险的最优分配，选中一套契约 DAG 执行。赛前再上一层**元策略**：不是选「一个策略」，而是维护一个策略组合（保守/均衡/激进），按对手类型与赛制（小组赛 vs 淘汰赛）选混合分布，追求在对手分布上的期望名次而非单场胜率。

## 1. 形式化定义（增量：定义 38–43）

**定义 38（技能契约 Skill Contract）**：一个技能契约是七元组 κ = (φ_pre, φ_post, I, G, C, ρ, π_κ)，其中 φ_pre/φ_post 为进入/退出状态谓词，I 为运行不变式，G 为安全约束（如 CBF 约束集），C = (θ, m_lo, T_hold) 为 v19 的证书三元组，ρ = (τ, γ, β) 为资源画像（时间、算力、**安全预算消耗**），π_κ 为执行该契约的低层控制器。**定义** κ 在预算 β 下 sound：∀x ⊨ φ_pre，π_κ 执行期间恒有 I、且 margin(x_t) ≥ θ、且 P(进入不安全集) ≤ β，并在 τ 内到达 φ_post。CKB 中每条记录即一个已证 κ。

**定义 39（分层分解 DAG 与组合算子）**：任务 T 的一个分解是 DAG D = (V, E, r)，叶节点为原子技能，内部节点为契约，边 i→j 表示 j 的 `pre` 必须由 i 的 `post` 满足。组合算子 ⊕：给定子契约 {κ_1,…,κ_k}，父契约 κ_⊕ = (φ_pre^1, φ_post^k, ⋀_i I_i, ⋃_i G_i, C_⊕, Σρ_i)，其中 C_⊕ 取保守合并 `θ_⊕ = max_i θ_i, m_⊕ = min_i m_i, T_⊕ = Σ_i T_hold^i`。**分解算子族** 𝔇(T) = {D : D 是 T 的合法分解}，粒度 |D| = 节点数。

**定义 40（接口证与组合可靠性）**：对每条边 i→j，接口证是一对 `(φ_post^i ∧ I_i ⇒ φ_pre^j, slack ε_ij)`，ε_ij 为蕴含的保守松弛量。**定理（组合可靠性）**：若每个子契约在其预算下 sound、且所有接口蕴含成立，则父契约 sound，且父边际下界 `m_parent ≥ min_i m_i − Σ_edges ε_ij`；父违规概率 `β_parent ≤ Σ_i β_i`（联合界）。推论：接口松弛是组合误差的唯一来源，`Σε` 必须计入证书对象并随计划下发。

**定义 41（安全预算与消耗）**：一场比赛/一轮允许的总体违规概率为 δ_match。策略层持有预算 β_total = δ_match − β_reserve（β_reserve 为未知风险的预留，建议 ≥40%）。对候选计划 `D` 的分配 `β = {β_i}`，要求 `Σ_i β_i ≤ β_total` 且 `β_i ≥ β_min`（低于此则该契约不可信，退化为保守变体）。**安全预算账本** L = (β_total, 已消耗, 剩余, 契约→β 映射) 是运行期一等公民。

**定义 42（比赛策略约束 POMDP）**：M = (S, A, T, O, R, δ_match, H)。状态 s = (Δscore, t_left, b_opp, health, L)；动作 a = (选择计划 D ∈ 𝔇(T), 预算分配 β, 加速/降级档 j)；观测 o = 对手动作 + 自身执行统计；奖励 R = 即时得分增量 − λ_pen·违规指示。目标：`max_π E[Σ_t R_t] s.t. P(∃t: unsafe_t) ≤ δ_match`。用拉格朗日对偶把机会约束折进即时惩罚：`R_λ = score − λ(β_total 消耗 − δ_match)_+`，λ 由在线对偶更新 `λ ← [λ + η(β_consumed − δ_match)]_+` 保证长期约束满足。

**定义 43（对手信念与元策略）**：对手类型空间 Θ，信念 b(θ) 由贝叶斯更新 `b'(θ) ∝ P(o | θ, a) b(θ)`。策略组合 Π = {π_1,…,π_m}（对应不同 λ / 不同分解偏好）。单场最优响应 `π* = argmax_π E_{θ∼b}[V_λ(π,θ)]`；锦标赛元策略为混合分布 `σ ∈ Δ(Π)`，优化目标为在对手先验分布 𝒟_opp 上的期望名次 `max_σ E_{θ∼𝒟_opp} rank(σ, θ)`，并以最小最大后悔约束防止对本地对手过拟合：`Regret(σ) = max_θ (V(π^BR(θ),θ) − V(σ,θ)) ≤ ε_regret`。

## 2. 新产出设计（增量 IP-57/58/59 + 升级 IP-51/52/55/54/56/47/50/45）

### 2.1 IP-57 HIER-CERT-PLANNER（分层证书规划器 HCP）
1. **契约库检索分解**：给定任务 T 与任务指纹 φ，从 CKB（IP-55）检索可复用的契约片段，做 HTN 式递归分解；每个候选分解立即得到组合证书与接口松弛账本。
2. **粒度自动调优**：枚举/剪枝候选分解，代价函数 `J(D) = Σ_i VerifyCost(κ_i) + InterfaceRisk(D) + λ_gran·|D|`，其中 InterfaceRisk(D) 由历史接口失配率与 Σε_ij 估出；输出最优深度 d*（通常 3–6 层）。
3. **接口综合**：对 `post_i ⋠ pre_j` 的缺口，自动生成「适配器契约」（小段 bridging 动作），并把适配器本身纳入验证；适配器失败即回退到更细分解。
4. **可证伪分解**：对每套分解给出「反例种子集」（最可能撕开接口的边界状态），交给 IP-54 SCV 做定向压力测试。

### 2.2 IP-58 MATCH-STRATEGIST（比赛策略器 MST）
1. **比赛状态编码**：`(Δscore, t_left, 剩余安全预算, 对手信念摘要, 健康度, 当前模式)` → 轻量网络 + 规则安全壳。
2. **计划竞标与预算分配**：对 𝔇(T) 中每个候选计划计算 `(E[score], β_needed, τ_needed, confidence)`，在 `Σβ ≤ β_total`、`Στ ≤ t_left` 下解一个带风险约束的背包/线性分配，返回选中计划与逐契约预算。
3. **机会约束对偶**：用拉格朗日乘子 λ 做在线风险定价；领先/时间充裕时 λ 自动升高（变保守），落后/末段时 λ 降低（变激进），但硬约束 `P(unsafe) ≤ δ_match` 由 SafeStop 兜底不可越过。
4. **在线重规划**：每 T_replan（如 200ms）或以事件（对手切换、健康度下降、预算超支）触发，重解；两次决策间用单调保守降级（承接 IP-52）避免抖动。

### 2.3 IP-59 TOURNAMENT-META（锦标赛元策略器 TMT）
1. **对手画像库**：从历史对局与在线观测维护对手类型分布（激进抢分/稳健防守/依赖特定技能），离线用自博弈扩充。
2. **策略组合与混合**：维护 {保守, 均衡, 激进} 三条 λ 曲线及各自分解偏好，赛前按赛制（小组赛重期望、淘汰赛重下限）选混合。
3. **鲁棒选择**：以 `(期望名次, 最小最大后悔)` 双目标选 σ，拒绝在本地对手上过拟合的脆弱策略。
4. **赛后归因**：每场输出「预算消耗轨迹 + 每次冒险的期望收益/实际结果」，供人工复盘并更新元策略先验。

## 4. 实验设计（E87–E94 硬门槛，承接 E79–E86）

| 实验 | 指标 | 门槛 |

| E88 分解粒度调优 | `J(D)` 相对最优的 regret；合成+验证总时间 vs 单块证书 | regret ≤ 10%；总时间降 ≥ 5x |

| E93 在线策略延迟 | 重规划 p99 延迟；事件触发到新计划生效 | < 20ms；< 50ms |

回退：E87 接口误差超界 → 细化分解或插入适配器契约，仍超则退回 v19 整块证书；E89/E90 出现 unsafe → 冻结 λ 下限、δ_match 减半，回到纯保守策略；E92 元策略无提升 → 关闭 TMT，固定均衡策略；E93 超时 → 策略降频到 1Hz 并用规则壳兜底。

## 5. 本轮最大风险

**一句话**：最危险的是「用被低估的违规概率去花安全预算」——一旦机会约束 POMDP 的尾部风险被仿真迁移界或对手模型系统性低估，系统会在比分压力下**主动把安全余量压到零**，把 v19 的「静默失效」从工程问题升级为「策略性冒险」，且赛后难以归因到底是策略错还是证书错；因此 E87（组合可靠性）与 E90（预算校准）必须作为红线，且 λ 与 δ_match 的调整权不得交给学习器，只能由人工设定硬边界。

# 第 43 轮产物 · 创新点清单 v20：策略感知的任务分解（HCP × MST × TMT）× 可竞标技能契约（四层架构 v8）

> 承接第 42 轮产物 v19。本轮**增量插入** IP-57/58/59，并升级 IP-51/52/55/54/56/47/50/45；不推倒 v19 的 Sim-Cert-RAG 飞轮，而是在其**上方**加「战略层 S」与「契约层 C」，把 v19 的「一张整机证书」改造成「可组合、可竞价、可复用的技能契约树」。

### IP-57 HCP：分层分解 + 接口综合 + 粒度调优

```
def decompose_with_contracts(task, phi, CKB, max_depth=6):
    # 1) 从契约知识库检索可复用的分解片段（承接 IP-55 RAG）
    seeds = CKB.retrieve_contracts(phi, k=8)
    # 2) HTN 递归分解，记录每套候选 DAG
    candidates = []
    def rec(subgoal, depth, dag):
        if is_primitive(subgoal) or depth >= max_depth:
            dag.add_leaf(as_contract(subgoal)); candidates.append(dag.copy()); return
        for m in methods(subgoal, seeds):          # 分解方法（含 CKB 片段）
            child = dag.extend(m.parts)
            if interface_ok(child):                 # 快速接口可行性剪枝
                rec(m.subgoal, depth+1, child)
    rec(task.goal, 0, empty_dag())
    # 3) 对每个候选算组合证书 + 接口松弛账本，再按 J(D) 选最优
    best = min(candidates, key=lambda D: plan_cost(D))
    return best

def interface_ok(dag):
    # 检查所有边 i->j: post_i ∧ I_i ⇒ pre_j；不满足则待插适配器
    return all(implies(edge.src.post & edge.src.I, edge.dst.pre)
               for edge in dag.edges)

def synthesize_adapter(post_i, pre_j, budget=2s):
    # 为 post_i ⋠ pre_j 的缺口生成最小 bridging 契约（本身也要被验证）
    delta = gap_region(post_i, pre_j)
    adapter = search_bridging_skill(delta, budget=budget)
    return adapter   # 失败则返回 None → 触发更细分解

def plan_cost(D):
    verify = sum(verify_cost(k) for k in D.nodes)
    interface_risk = sum(hist_mismatch_prob(e) + LAMBDA_EPS * e.eps
                         for e in D.edges)
    return verify + interface_risk + LAMBDA_GRAN * len(D.nodes)

def assemble_composed_cert(D):
    # 组合证书（保守合并）+ 父边际下界（计入接口松弛）
    theta = max(k.C.theta for k in D.nodes)
    m_min = min(k.C.m_lo for k in D.nodes)
    eps_sum = sum(e.eps for e in D.edges)
    beta_sum = sum(k.rho.beta for k in D.nodes)
    return Certificate(
        theta=theta, m_lo=m_min - eps_sum,     # 组合误差显式入账
        T_hold=sum(k.C.T_hold for k in D.nodes),
        beta=beta_sum,
        interface_ledger=[(e, e.eps) for e in D.edges])
```

### IP-58 MST：计划竞标 + 安全预算分配（机会约束）

```
def plan_match(belief_state, candidates, ledger, delta_match, reserve=0.4):
    s, t_left = belief_state, belief_state.t_left
    beta_total = (1 - reserve) * delta_match
    # 1) 每个候选计划“报价”：期望得分、预算需求、时间、置信度
    bids = []
    for D in candidates:
        cert = assemble_composed_cert(D)
        bids.append({
            'D': D, 'score': expected_score(D, s, belief_state.b_opp),
            'beta': cert.beta, 'tau': cert.T_hold,
            'conf': cert.confidence, 'cert': cert})
    # 2) 带双约束（预算+时间）的风险调整背包
    #    maximize Σ x_D·score_D  s.t.  Σ x_D·beta_D ≤ beta_total, Σ x_D·tau_D ≤ t_left
    chosen = risk_aware_knapsack(bids, beta_total, t_left, lambda_price=ledger.lambda_)
    # 3) 逐契约预算分配：按“边际收益/边际预算”排序，保证每个 ≥ β_min
    alloc = allocate_budget(chosen.D, chosen.beta, beta_min=BETA_MIN)
    return chosen.D, alloc

def update_lambda(ledger, delta_match, eta=0.05):
    # 机会约束拉格朗日对偶：超支则抬价（变保守），有余则降价（变激进）
    ledger.lambda_ = max(0.0, ledger.lambda_ + eta * (ledger.consumed - delta_match))
    return ledger.lambda_

def match_replan_loop(state, hcp, mst):
    plans = hcp.enumerate(state.task)
    last = None
    while not terminal(state):
        event = wait_event(timeout=200ms)      # 定时或事件驱动（对手切换/健康下降/超支）
        if event or last is None:
            D, alloc = mst.plan_match(state, plans, state.ledger, DELTA_MATCH)
            if not hysteresis_ok(last, D):      # 抖动抑制：保留旧计划一步
                D, alloc = monotone_downgrade(D, alloc)
            dispatch_contract_dag(D, alloc)     # 热替换 CAR 子自动机
            last = (D, alloc)
        state = observe_and_update(state)       # 更新对手信念 b(θ) 与预算账本
```

### IP-59 TMT：对手画像 + 策略组合 + 元策略选择

```
def meta_select(opp_prior, Pi, tournament_format):
    # Π = {保守, 均衡, 激进} 三条 λ 曲线 + 各自分解偏好
    best, best_val = None, -inf
    for sigma in simplex_grid(len(Pi)):
        exp_rank = expected_rank(sigma, opp_prior)
        regret = max_regret(sigma, Pi, opp_prior)   # 对 best-response 的最小最大后悔
        val = w_rank * exp_rank - w_regret * regret
        if val > best_val:
            best, best_val = sigma, val
    return best

def update_opponent_belief(b, obs, opp_model):
    pred = {theta: opp_model[theta].likelihood(obs) for theta in b}
    z = sum(b[theta] * pred[theta] for theta in b)
    return {theta: b[theta] * pred[theta] / z for theta in b}

def post_match_attribution(log):
    # 预算消耗轨迹 + 每次“冒险”的期望收益 vs 实际结果
    return [{'plan': e.plan_id, 'beta_spent': e.beta, 'exp_gain': e.exp_gain,
             'real_gain': e.real_gain, 'unsafe': e.unsafe} for e in log.events]
```

### 升级：契约级 CAR 与预算感知 LCS

```
def car_contract_guard(kappa, x, cert_obj, eps_in, beta_i):
    # 阈值同时含 Sim-to-Real 修正 α_e、接口松弛 ε 与预算压力（预算越紧越保守）
    theta_real = cert_obj.alpha_e[kappa] * cert_obj.theta_sim[kappa] \
                 + risk_margin(eps_in, beta_i)
    margin = cert_lookup_L0(x, budget_tier=beta_i).m_lo[kappa]
    return margin >= theta_real

def certify_light_budgeted(x, guards, budget_us, beta_i):
    # T-1: L0 查表（预算档参与键，返回该档 j*）
    b = cert_lookup_L0(x, budget_tier=beta_i)
    U = undecided_guards(b, guards)
    if not U: return b, -1
    # T0: L1 INT8 监控器，仅在剩余时间/预算允许时上调档位
    if budget_us < 110: return downgrade_monotone(b), -1
    status, margin, conf = monitor_step_INT8(quantize_obs(x))  # conf 供 MST 定价
    b.m_lo, b.conf = margin, conf
    U = undecided_guards(b, guards)
    return (b, 0) if not U else (downgrade_monotone(b), 0)
```

| 风险 | 等级 | 缓解措施 |

## 6. 本轮最大风险

**一句话**：最危险的是「用被低估的违规概率去花安全预算」——一旦机会约束 POMDP 的尾部风险被仿真迁移界或对手模型系统性低估，系统会在比分压力下**主动把安全余量压到零**，把 v19 的「静默失效」从工程问题升级为「策略性冒险」，且赛后难以归因到底是策略错还是证书错；因此 E87（组合可靠性）与 E90（预算校准）必须作为红线，且 λ 与 δ_match 的调整权不得交给学习器，只能由人工设定硬边界。
