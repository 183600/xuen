## 0. 本轮先核实：八个新事实

### 0.1 接口 v2：四路相机、EE 动作、chunk 是整段执行的
`unibot_submission` README（v2，最后提交 `edd0a1c9`，2026-08-21）给出：

- 观测四路 RGB：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`（480×640）；双臂关节 `[7]`、EE pose `[6]`（xyz+rpy）、夹爪开度 `[1]`、下半身 `[15]`、语言单字符串。**没有 torque/force 观测。**
- 动作空间 `joint` 或 `ee` 互斥；EE 模式输出 `action.left/right_ee_pose_gripper_base`（xyz+rpy），另有 `action.left/right_gripper`、`action.pivot`。
- `obs_delta_indices` 自选观测与堆叠帧；`image_resize` 自定分辨率；`action_chunk_size` 自定。
- **关键**：`action_chunk_size` 是每次 `get_action` 返回的动作步数；evaluator 先执行 index 0，再按顺序执行其余，直到下一次调用。也就是说，**chunk 是整段执行的**，不是"返回 8 步但只执行 1 步"。要做逐步接触闭环，必须把 `action_chunk_size` 降到 1–2，或者在 chunk 内做"首步动作 + 后续保持/阻尼"的安全填充。
- evaluator 逐调用记录延迟与动作统计，并用于结果可信度评估——延迟要稳定，不能靠抖动换性能。

这条接口事实直接决定了本轮方案的控制频率与 chunk 策略（见 §3 与产物区 §4.3.3），也解释了为什么上轮的"相位感知 chunk"不能照搬 PACE 的变 horizon：**API 的 horizon 是声明死的，只能在 chunk 内容或 chunk size 上做文章。**

### 0.2 数据里的 EE 跟踪残差确实是"接触/负载"信号
我对官方数据的两个任务做了离线实测（方法见产物区 §2）：

- **HangCup**（`file-001`，324 eps / 63,999 帧）：右臂 EE 位置跟踪误差 p50 **17.5mm**、p90 34.2mm；左臂 p50 **11.7mm**。右臂在夹爪闭合持杯段（g<0.5）p50 **21.0mm**，张开段（g>3.5）**14.5mm**；z 轴 **18.1mm vs 9.9mm**；低速（<20mm/s）子集仍是 **21.1mm vs 14.6mm**，排除"只是速度造成的滞后"。
- **PlugCharger**（`file-003`，169 eps / 70,910 帧）：右臂整体 p50 **13.1mm**，但插入段（进度 60–80%、夹爪半闭）p50 **54.2mm**、p90 101.3mm；同段张开帧只有 **13.3mm**。对速度拟合后的残差：插入段 p50 **+40.5mm**、p90 +88.6mm，张开段 p50 **+1.0mm**。
- 位置环一阶 ARX 拟合（30Hz）：HangCup 右臂 **R²≈0.999、等效时间常数≈99ms**；PlugCharger 右臂 R²≈0.998、≈284ms（慢速/接触段拉长）。这说明动作是位置目标、状态是平滑响应，**残差不是简单的对齐错误，而是低频负载代理**。
- 但它是**有条件的强信号**：PlugCharger 插入段 vs 自由段 AUROC **0.866**（5% FPR 下 TPR 75.7%）；HangCup 轻纸杯持握 vs 自由段 AUROC 只有 **0.722**（5% FPR 下 TPR 12.5%）。轻物体的负载太小，单靠残差不够，必须与夹爪、相位、视觉融合。

### 0.3 相位条件化不是可选项，是必需项
同一个 PlugCharger 右臂：把全部"半闭"帧和"张开"帧混在一起，AUROC 只有 **0.645**；只取插入段（60–80%）对自由段，AUROC 升到 **0.866**。**聚合统计会把接触信号平均掉。** 这直接支持"任务/相位画像卡 + 相位条件诊断"，而不是一个全局阈值。

### 0.4 人类干扰与未见物体有逐任务剧本
32 个 `info.json` 的 `generalization` 字段给出 `human_1_note` / `human_4_note` / `unseen_object_3`。例如 T27「叠了第二个之后拿下第二个」（先叠后撤）、T19「拉上拉链之后拉开」、T14「拧开盖子之后拧动回来」、T24「可乐/薯片快到了然后放回传送带起点」。这些不是抽象轴，而是**可回放的 1-DOF 干扰脚本**；它们应该进入画像卡的 `disturbance_script`，并让诊断器"预期"一个 undo 事件，而不是等失败后再猜。

### 0.5 HumanoidVLM 已在 G1 上证明"位置接口 + 虚拟阻抗"可行
HumanoidVLM（arXiv 2601.14874，2026-01）明确写：**Unitree G1 没有腕部力/力矩传感，两指夹爪也没有反作用 wrench 反馈**；它用任务空间质量-弹簧-阻尼模型生成虚拟参考，再通过 G1 内置位置控制器执行，控制频率 50Hz；在 9 个任务、14 张测试图上检索准确率 93%，z 轴跟踪误差通常 1–3.5cm，虚拟力与阻抗设置一致。

这证明"无传感器柔顺"在 G1 上不是纸上谈兵。但它的边界也很清楚：9 个任务、手工数据库、4090 外挂 VLM+FAISS、每 episode 检索一次、固定任务级 K/D。**我们要做的是把任务级检索升级为相位级闭环，并把画像、诊断、恢复接进来。**

### 0.6 PACE 证明"相位感知执行"是训练免费的
PACE（arXiv 2606.00537）用预测 chunk 的速度剖面找低速过渡点，在线选择执行 horizon；50 个 RoboTwin2.0 任务 57.8%→64.2%，真机双臂/单臂 **50.7%→70.4%**，任务分 **60.7→77.7**。它只改执行、不改策略，正好适配"单模型 + 位置接口"。

但 UniBot 的 chunk 是整段执行的（§0.1），所以不能直接照搬"变 horizon"；正确做法是 **chunk size 1–2 + 内部缓存**，或在 chunk 内做相位相关的阻尼填充。

### 0.7 VLA-FAIL / FIPER 证明"无失败数据"也能做运行时诊断
- VLA-FAIL（arXiv 2606.21386）：LLMD（last-layer Mahalanobis）+ ACC（action chunk consistency），不需要失败数据，用 AUCPDT 联合评估准确率与检测时延。
- FIPER（arXiv 2510.09459）：OOD（RND）+ action-chunk entropy，两个指标用成功 rollout 做 conformal 校准，也不需要失败数据。

这给诊断器一个可复用的骨架：**成功演示校准阈值 + 多通道证据融合**。我们的增量是把"控制级接触残差"和"任务级相位/画像"接进同一个证据图，并让诊断输出**代价感知的恢复动作**，而不只是报警。

### 0.8 榜单/规则仍是占位/未读全，不能据此调参
`leaderboard.html` 仍「即将发布」，`runs.html` 仍是 256/256 占位，details 页写「测试视频占位」；榜首 29.7%/39.0 不能当真实上限。Feishu 规则只读到 2.2（数据资源），**2.3 之后的外部数据/预训练权重政策仍未核实**。因此本轮所有"外部数据/合作"默认 OFF，靠官方 33k + 平台调试槽。

## 1. 三个灵感词，各自钉到一个可落地模块

| 灵感词 | 官方事实 | 模块 | 主要指标 |
|---|---|---|---|
| 阻抗控制 | G1 无腕部 F/T；API 只有位置/夹爪；位置环有 ~100ms 平滑 | **SCC**：Sensorless Contact Compliance，残差观测 + 导纳外层 + 相位感知执行 | 终局步成功率、接触段成功率、时间 |
| 用户画像 | 32 任务 × 5 复述 × 5 泛化轴；逐任务评分步骤 + 人类干扰剧本 | **TPC**：Task Profile Card，评测者/任务画像卡 + 条件画像 | 画像覆盖率、OOD 轴回归、误报率 |
| 故障诊断 | 成功=全步骤；320 trials；人类 undo 剧本；无失败数据 | **Dx**：多通道诊断 + F1–F9（上轮 P1–P6 扩展）+ 代价感知恢复 | 诊断 AUROC、恢复成功率、误报/耗时 |

### 1.1 阻抗控制 → SCC：不是新低层控制器，是位置接口上的导纳外层
我们不需要改 G1 的底层控制，也不能读力。SCC 做三件事：

1. **残差观测器**：用成功演示拟合"自由空间跟踪误差 vs 速度"的基线，当前误差减基线得到负载残差 `r_t`；低通后作为接触/负载代理。
2. **导纳外层**：把策略的 EE 目标 `x^π` 加上一个受限位移 `Δx = -A r̄`（各向异性 A：插入轴更软、正交轴更硬），限幅、限速、死区；这就是"用位置指令实现虚拟阻抗/导纳"。
3. **相位感知执行**：接触段 chunk 降到 1–2 步（或 chunk 内保持），自由段长 chunk；用 PACE 的低速过渡点做兜底。

**边界**：残差是低频负载代理，不是力传感器；只做准静态接触（插入、放置、拧/压），不做高频力控。轻物体信号弱时，退回夹爪/相位/视觉融合。

### 1.2 用户画像 → TPC：把"评测者"当用户，而不是 C 端用户
这里的"用户"是**评测者/任务分布**：它给每个任务 5 条复述、10 次试验、5 类泛化条件、逐任务评分步骤和人类干扰剧本。画像卡不是人口统计学画像，而是**任务交互画像**：

- **最小版**：32 张 JSON 卡，字段包括评分步骤、接触模式序列、各模式的夹爪/残差/速度分布、控制参数（K/D、chunk horizon、接近速度）、失败先验、人类干扰脚本、恢复库、时间预算。卡由官方 metadata + 演示统计生成，运行时只做查表/插值，**不跑 VLM**。
- **研究版（CMV）**：对 33k 演示做无监督接触模式发现（变化点/HMM + 聚类），得到跨任务的接触模式词表（free / approach / grasp / transport / contact / insert / release / retract），再把每张卡表示为"模式序列 + 转移矩阵 + 模式条件残差分布"。运行时用前向滤波估计当前模式，控制器和诊断器都条件在模式后验上。

这比 HumanoidVLM 的 9 任务 VLM-RAG 更适合比赛：32 任务、160 复述、延迟敏感、无 4090 外挂；而且画像是**数据/配置**，不是第二个模型，单模型合规。

### 1.3 故障诊断 → Dx：从"报警"到"代价感知的恢复"
证据通道：

- `r_t`：接触残差（控制级）
- `ACC`：相邻 chunk 的一致性（策略级）
- `H`：action entropy / LLMD（OOD/不确定）
- `g_t`：夹爪开度 vs 画像期望（滑脱/空抓）
- `s_t`：SSG 步骤进度 vs 期望（卡住/假完成）
- `v_t`：视觉目标位移（人类 undo/掉落，可选）
- `m_t`：模式序列似然（画像级）
- `t`：剩余时间/重试预算

故障分类（在上轮 P1–P6 上扩展）：

| 编号 | 故障 | 主要证据 | 恢复 |
|---|---|---|---|
| F1 | 目标/槽位 grounding 错 | SSG + 视觉 + 谓词 | 重锚定/重规划 |
| F2 | 路径碰撞 | 残差突增 + 视觉 | 后退/绕行 |
| F3 | 姿态不对 | 残差 + 视觉 + 谓词 | 重伺服/旋转 |
| F4 | 释放过早/掉落 | 夹爪 + 视觉 + 谓词 | 重抓/重放 |
| F5 | 插入深度/接触不足 | 残差 + 进度停滞 | 后退 + wiggle/spiral + 重插 |
| F6 | 假完成 | 谓词 + 视觉 | 校验 + 重试 |
| F7 | 接触失稳/力不匹配 | 残差方差 + ACC | 降增益/减速/再接近 |
| F8 | 外部干扰/undo | 视觉变化 + 模式序列反转 | 重做受影响步骤 |
| F9 | 策略 OOD/不确定 | LLMD/entropy/ACC | 保守回退/重锚定 |

恢复选择是**代价感知**的：`a* = argmax_a [P(success|F,a,card) - λ·time(a) - μ·risk(a)]`，并加"不做坏"约束：除非 F6/F8，不撤销已完成步骤；每步最多 1–2 次恢复；总时长 <180s。

## 2. 本轮主判断：最后 3 厘米是"控制 + 诊断"问题，不是"再堆视觉"

### 2.1 为什么是现在
- 头部模型（MolmoAct2、Wall-OSS-0.5、DreamZero、GigaBrain-0、π0.5、GR00T N1.5）几乎都是**视觉输入 + 位置动作**；它们把"接触"留给底层位置控制器。DreamZero 14B WAM 的闭环只有 7Hz，更不可能靠它做 30Hz 接触闭环。
- 官方 API 明确没有 torque/force；G1 也没有腕部 F/T（HumanoidVLM 已确认）。想在最后 3 厘米做柔顺，**只能从位置跟踪残差里"读"出接触**。
- 我们的离线数据证明这个信号存在，且**在插入段很强、在轻物体持握段较弱**——这正好定义了 SCC 的能力边界和 Dx 的融合必要性。
- HumanoidVLM、PACE、VLA-FAIL、FIPER 分别证明了"位置接口虚拟阻抗""相位感知执行""无失败数据诊断"可行；**据本轮检索，尚未见到把它们合成一个 32 任务、单模型、无力的运行时层**。

### 2.2 与头部模型的关系：模型无关的外层，不是又一个 VLA
PACT 不训练新策略，也不改底座权重；它把任意 VLA 的 EE 目标当**名义参考**，在外层做柔顺、诊断、恢复。好处：

- 底座可以换：GPR-VLA、MolmoAct2、Wall-OSS-0.5 都能套；优先 GPR-VLA，若算力允许再做第二个底座的接口测试。
- 计算便宜：SCC/Dx 是轻量确定性代码（目标 <5ms/step），VLA 可以 7–30Hz 缓存调用。
- 单模型合规：唯一学习模型是底座；画像是 JSON/HMM，不是第二个网络。
- 与上轮资产兼容：SSG 提供相位/步骤，PGL 提供放置目标，OPT 提供相对位姿，SVL 并入 Dx。
- 画像只用官方公开 metadata + 训练演示，不碰评测集/榜单；规则若禁止使用 generalization 备注，则退回通用扰动先验。

## 4. 风险与合规（先立后破）

- **残差弱**：轻物体持握 AUROC 只有 0.72；单靠残差会漏检。必须融合夹爪/相位/视觉；若融合后仍 <0.7，SCC 只做插入/放置类任务，不做通用柔顺。
- **低层控制器未知**：评测端的 Kp/Kd、是否有积分、控制频率未公开。SCC 的增益必须在调试槽标定；若残差与负载无单调关系，停止 SCC，退回固定增益 + Dx。
- **chunk 接口**：`action_chunk_size=1` 会放大网络调用与延迟；若评测延迟不稳，退回 2–4 步 chunk，并在接触段用"首步 + 保持"填充。延迟稳定性本身是可信度指标。
- **画像过拟合**：32 张卡可能记住任务而不是接触物理；用 CMV/HMM 的跨任务模式词表降低过拟合，并在未见物体/人类干扰轴上做回归测试。
- **单模型审计**：VLA 是唯一学习模型；TPC 是 JSON/表，SCC/Dx 是确定性代码；模型卡写清楚，避免"隐藏第二个模型"的嫌疑。
- **规则未读全**：Feishu 2.3+ 的外部数据/预训练权重政策未知；L2L/外部数据默认 OFF，邮件确认后再开。
- **调试槽稀缺**：不计分单任务调试的次数/成本未知；把调试槽当"机制验证"而不是"调参器"，每个大版本最多 1 槽。
- **统计噪声**：320 trials 的单次估计 SE≈2.6pp（95% CI 约 ±5pp）；两次独立跑的差异 SE≈3.6pp，+5pp 约 1.4σ、+3pp 约 0.8σ；必须任务配对/bootstrap，不追 +1–2pp。
- **人类 undo 检测**：视觉变化可能被机械臂自身遮挡；先做"状态/谓词反转"检测，视觉只做辅助，避免误报。

**把最后 3 厘米从"策略问题"改写成"控制 + 诊断问题"：用 33k 官方演示离线标定 EE 跟踪残差，用 32 张评测者画像卡调度无传感器导纳与相位感知执行，用多通道诊断做代价感知恢复；它不改单模型、不要力传感器，直接套在任意强 VLA 外面——这是本轮最值得押注的方向。**

## 2. 数据证据：EE 跟踪残差作为接触/负载代理

### 2.1 方法（可复现）

对每个数据集/臂：

1. 读取 `episode_index`、`frame_index`、`timestamp`、`observation.state.*_ee_pose_gripper_base`、`action.*_ee_pose_gripper_base`、`observation.state.*_gripper`；只保留 `recomputed_ee_valid==1`。
2. 按 episode 分组，动作/状态在 **lag 0** 对齐（实测 lag 0 的 p50 最小；lag 1–6 单调变差，说明数据已同步，残差不是对齐错误）。
3. 位置误差 `e_t = ||a_t - s_t||`；z 误差 `e_z = |a_z - s_z|`；关节误差 `||q^a - q^s||`。注意 `e_t` 同时包含「下一步目标相对当前状态的期望位移」与「跟踪误差」；第 4 步的自由空间拟合 `e~v` 把与速度成正比的期望位移吸收掉，残差才是负载代理。
4. 自由空间基线：在张开帧（`g>3.5`）上拟合 `e_t ≈ a + b·v_t`（`v_t` 为 EE 速度），得到 `ê_free(v)`；负载残差 `r_t = e_t - ê_free(v_t)`。选线性模型是因为它可解释、在低速段稳定；高阶模型留作消融。
5. 相位：`progress = (frame - min)/(max - min)` per episode；10 个 bin。
6. 夹爪分组：`open = g>3.5`，`mid = 0.5≤g≤3.5`（半闭/持物），`closed = g<0.5`（闭合/抓取瞬态）。
7. 检测指标：rank-based AUROC；阈值取负样本（自由段）的 95/99 分位，报告 TPR/FPR。
8. ARX：`s_t = a·s_{t-1} + b·a_{t-k} + c`，逐轴最小二乘，k=0..6；报告 R²、a、b、等效时间常数 `τ = -dt/ln(a)`（dt=1/30s）。

> 复现脚本：`/tmp/analyze_track3.py`（本次会话生成）；数据文件：`/tmp/hang_001.parquet`、`/tmp/plug_003.parquet`。脚本只依赖 `pyarrow` + `numpy`。

### 2.3 解释与边界

- **为什么插入段强**：插头/插排接触后，位置环被负载顶住，命令继续走、状态跟不上，残差沿插入轴累积；半闭夹爪（mid）正好标记「持物插入」阶段。这与「位置误差 ∝ 外力 / 位置环刚度」的经典关系一致，但我们没有标定绝对力。
- **为什么轻物体弱**：纸杯质量小，负载残差只有几毫米，和自由空间的速度残差同量级；单靠残差无法可靠区分「持杯」与「空载」。需要夹爪状态、相位、视觉（杯子是否随手移动）融合。
- **替代解释**：残差也可能来自策略自身的动作不平滑、关节限位、或低层控制器的积分项；我们用低速子集、自由空间基线、相位分组做了控制，但不能排除。**它是相关性证据，不是力标定。**
- **不能做什么**：不能用它做高频力控、不能估计绝对接触力、不能在未知低层控制器上保证单调性；它只适合做「接触/负载模式」的低频证据和增益调度。
- **数据局限**：只用两个任务的文件；成功演示为主；夹爪单位未标定；没看图像；没做跨任务/跨机器人验证。帧级 AUROC 的帧间相关很强，有效样本远小于帧数；表中是点估计，CI 需按 episode 聚类 bootstrap。结论要标「在 HangCup/PlugCharger 上成立」。

### 2.4 对控制的含义

1. **带宽**：位置环 τ≈100ms → 导纳外环截止频率 ~1–2Hz；每 1–2 个控制步更新一次，避免和低层位置环打架。
2. **阈值**：按任务/臂/模式分别标定；用成功演示的 95/99 分位 + conformal，而不是拍一个全局 mm 数。
3. **各向异性**：插入轴（通常是 z）更软、正交轴更硬；残差沿插入轴的分量驱动 Δz，正交分量只做小修正。
4. **安全**：Δx 限幅 5–10mm（搜索时 20mm）、限速 20mm/s、死区 2–3mm；残差持续超安全阈值 → 交给 Dx，不硬顶。
5. **回退**：若某任务/臂的残差与负载无单调关系（标定失败），SCC 关闭，只保留 Dx + 固定增益。

## 3. 评分算术与统计功效

### 3.1 终局/接触仍是闸门

上轮已算：32 个任务的终局步骤合计 **1275/3200 分（39.8%）**；放置/插入/堆叠/闭合类步骤约 **59.7%**；成功 = 所有步骤完成，终局是 32/32 的闸门。本轮把其中真正有接触动力学的候选任务列为：T05、T07、T10、T12、T14、T19、T26、T27 等（约 14–15 个，待按 `info.json` 逐条复核）。这些任务的共同点是：最后一步不是「到达」，而是「压/插/拧/倒/拉/叠/放稳」。

### 3.2 320 trials 能证明什么

- 每个任务 10 trials，p≈0.3 时单任务 SE≈14.5pp；32 任务平均 SE≈**2.56pp**；95% CI≈±5pp。
- 两次独立 320-trial 跑的差异 SE≈**3.6pp**；+5pp 约 1.4σ，+3pp 约 0.8σ——**单次计分跑不足以证明 +3pp**。
- 若同一批 episode 配对（或任务配对 + bootstrap），差异方差可下降；+5pp 可到 ~2σ。预注册主指标（平均成功率）+ 任务配对 bootstrap，报告 CI，不追 +1–2pp。
- 因此本轮的 Go/No-Go 是「机制验证 + 至少 +5pp 的保守效应」，不是「+2pp 也算赢」。

### 3.3 预期增益（保守/乐观）

| 情形 | 假设 | 全局成功率 | 步骤分 |
|---|---|---:|---:|
| 保守 | 14/32 接触任务终局 +5pp，其余不变 | +2.2pp | +2–3pp |
| 基准 | 14/32 接触任务终局 +10pp | +4.4pp | +4–6pp |
| 乐观 | +10pp 且掉落/碰撞减少 2pp | +5–7pp | +6–8pp |
| 失败 | 残差在真机不成立 | 0 或负 | 0 或负 |

> 结论：值得做，但必须先用调试槽验证「残差→接触」在真机上成立；如果离线/调试槽的 AUROC <0.75，停止 SCC，只保留 Dx。

## 4. PACT 架构

### 4.1 总览与设计原则

```text
语言 + 首帧
   │
   ▼
TPC 画像卡（32 张；JSON / HMM）
   │ 模式先验、残差分布、失败先验、干扰剧本、控制参数
   ▼
VLA（单一 checkpoint；7–30Hz；缓存 chunk）
   │ 名义 EE 轨迹 x^π
   ▼
SCC（与 evaluator 同步；数据 30Hz；残差 + 导纳 + 相位执行）
   │ 实际动作 x^π + Δx
   ▼
机器人 ──► 观测（EE/夹爪/图像）
   │
   ▼
Dx（10–30Hz；证据融合 + F1–F9 + 代价感知恢复）
   │ 恢复动作 / 继续
   └──► SCC / VLA
```

设计原则：

1. **模型无关**：VLA 只提供名义轨迹；PACT 不改权重、不假设具体架构。
2. **训练免费**：SCC/Dx/TPC 都是确定性代码或离线统计；唯一学习模型是 VLA。
3. **无传感器**：只用 EE 跟踪残差、夹爪、关节、图像；不假设 F/T。
4. **画像条件化**：同一套控制律，按任务/模式切换参数；避免 32 套手工控制器。
5. **代价感知**：诊断不是报警，是在时间/风险约束下选恢复动作。
6. **可回退**：任何模块失败都能退回「固定增益 + 原始 chunk」，不影响基线。

### 4.2 TPC：任务画像卡

#### 4.2.1 最小版（先做）

每张卡由官方 metadata + 训练演示统计生成（**不碰评测集/榜单**），运行时只查表/插值（下面的权重/模式数值是示意，实际以 `info.json` 与离线统计为准）：

#### 4.2.2 研究版：CMV（Contact-Mode Vocabulary）

最小版依赖人工命名模式，容易过拟合 32 个任务。研究版做**无监督接触模式发现**：

1. 对每条演示提特征：夹爪开度 `g`、残差 `r`（norm/z）、EE 速度 `v`、EE 高度 `z`、`Δg`、`Δr`、相位进度。
2. 用变化点检测（PELT）或 K-state HMM 分段；用 BIC 选 K（预期 6–8）。
3. 把所有段聚类成跨任务模式词表；按特征签名命名（free/approach/grasp/transport/contact/insert/release/retract）。
4. 用 DTW/规则把模式序列对齐到官方 `score_steps`（弱监督）。
5. 每张卡 = 模式序列 + 转移矩阵 + 模式条件残差/夹爪/速度分布 + 失败先验 + 干扰剧本。
6. 运行时用前向 HMM 滤波估计 `p(m_t|o_{1:t})`；控制器用后验混合增益，诊断器用模式条件阈值。

**研究问题**：跨任务模式词表是否比任务级手工卡更抗 OOD（未见物体/背景/人类干扰）？消融：最小版 vs CMV。

**合规**：HMM 是固定参数的统计模型，不是第二套策略网络；如果规则对「模型」定义极严，退化为规则式模式分类器（夹爪+残差+速度阈值），并在模型卡披露。

#### 4.2.3 条件画像

语言只给任务，不给泛化条件。条件画像从首帧/前 1–2 秒估计：

- 目标物体/容器的粗略位姿、尺寸、是否在场景中；
- 干扰物数量/位置（背景轴/干扰物轴）；
- 物体是否属于未见类别（视觉 OOD 分数）；
- 人类是否在画面内/是否靠近（人类干扰轴）。

条件画像不改变任务卡，只调阈值/参数：例如干扰物多 → 降低接近速度、提高 F2 先验；人类在画面 → 提高 F8 先验、缩短 chunk。

### 4.3 SCC：无传感器接触柔顺

#### 4.3.1 残差观测器

```text
e_t   = x^π_t - x^o_t                    # 位置跟踪误差（mm）
ê_t   = a + b·v_t                       # 自由空间基线（按任务/臂/模式拟合）
r_t   = e_t - ê_t                       # 负载残差
r̄_t   = LPF(r_t, τ_f)                   # τ_f ≈ 0.2–0.5s
```

- 只用**沿接近轴**的分量做主要判断；正交分量做小修正。
- 残差是低频信号；不要在每个控制步都更新 Δx，按 1–2Hz 或每 1–2 步更新。
- 死区 `|r̄|<δ_db` 不动作；δ_db 按自由段 p95 标定（HangCup 约 10–14mm，PlugCharger 约 15–22mm，按臂/任务调）。

#### 4.3.2 导纳外层

```text
Δx_t = clip( -A_m · r̄_t , -dx_max[m], +dx_max[m] )
Δx_t = rate_limit(Δx_t, v_max·dt)
x^cmd_t = x^π_t + Δx_t
```

- `A_m`：各向异性柔顺矩阵。自由段小（0.1–0.2）、接触/放置段可到 0.2–0.4、插入轴更大；数值由调试槽标定。
- `dx_max`：5–10mm；插入搜索可到 20mm。
- `v_max`：20mm/s；避免和低层位置环打架。
- 姿态：最小版保持策略的 rpy；可选在插入轴加 ±2° 的旋转柔顺（拧/插），但先不做。
- 夹爪：用画像卡的抓取角度/闭合量；SCC 不改夹爪命令（避免和力控耦合）。

#### 4.3.3 相位感知执行

- **推荐**：`action_chunk_size=1`（或 2），每次 `get_action` 返回一步；策略内部缓存 chunk，每 H 步才重新推理。这样 evaluator 每步调用，SCC 能拿到逐步反馈，VLA 推理被摊薄。
- **回退**：若延迟不稳/不允许 chunk=1，用 `action_chunk_size=4`；接触段 chunk 的后续步填「首步目标 + 保持」，避免开环冲过头。
- **H 的选择**：自由段 H=8–16；接触/插入 H=1–3；模式后验不确定时取中间值。PACE 的低速过渡点作为兜底（预测 chunk 的速度剖面找局部极小）。
- **延迟预算**：VLA 7–30Hz；SCC 与 evaluator 同步（数据 30Hz）；网络调用 1–2 次/步；若 p99 延迟 >100ms，退回 chunk=2–4，并把 SCC 更新降到 1–2Hz。

#### 4.3.4 伪代码

```python
class PACT:
    def __init__(self, vla, profile, scc, dx):
        self.vla, self.profile, self.scc, self.dx = vla, profile, scc, dx
        self.cache = None
        self.t = 0

    def act(self, obs):
        task = match_task(obs["language"])          # 160 条复述 → task_id
        card = self.profile[task]
        cond = self.profile.condition(obs)           # 首帧/在线条件
        if self.cache is None or self.t % self.horizon(obs, card, cond) == 0:
            self.cache = self.vla.plan(obs)          # 名义 EE chunk
        x_pi = self.cache[0][:3]
        x_o = obs["right_ee_pose"][:3]
        v = (x_o - self.prev_x) / DT
        e = x_pi - x_o
        r = e - self.scc.free_model(v, task, "right")
        r_f = self.scc.lowpass(r)
        m = self.profile.filter(obs, r_f)            # HMM 后验（或规则）
        A = self.profile.mix(card, m, "A")
        dx = self.scc.admittance(r_f, A, card, m)
        x_cmd = x_pi + dx
        self.dx.observe(r_f, m, card)                # 触发诊断
        self.prev_x, self.t = x_o, self.t + 1
        return make_action(x_cmd, self.cache[0][3:], obs, task)
```

> 说明：`make_action` 负责 EE→动作字典、夹爪/pivot、token、dtype/shape；`action_chunk_size` 为 1 时 `self.cache[0]` 就是当前步。

### 4.4 Dx：故障诊断与代价感知恢复

#### 4.4.1 证据

| 证据 | 计算 | 作用 |
|---|---|---|
| `r_t` | §4.3 残差 | 接触/负载异常；F2/F5/F7 |
| `ACC` | 相邻 chunk 重叠段的余弦/L2（比较策略内部两次重规划的完整 chunk；chunk=1 时仍可比较） | 策略不一致/OOD；F9 |
| `H` | action entropy / LLMD（若有特征） | OOD/不确定；F9 |
| `g_t` | 夹爪开度 vs 画像期望 | 空抓/滑脱；F4 |
| `s_t` | SSG 步骤/谓词进度 | 卡住/假完成；F1/F6 |
| `v_t` | 目标区域帧差/跟踪（可选） | 人类 undo/掉落；F8 |
| `m_t` | HMM 模式序列似然 | 模式反转/卡死；F7/F8 |
| `t` | 已用时间/重试次数 | 预算；abort |

#### 4.4.2 故障表（P1–P6 → F1–F9）

| 编号 | 故障 | 典型证据 | 恢复优先级 |
|---|---|---|---|
| F1 | 目标/槽位 grounding 错 | SSG 谓词不成立 + 视觉错位 | reanchor > replan > abort |
| F2 | 路径碰撞 | 残差突增 + 视觉近障 | backoff > reroute > abort |
| F3 | 姿态不对 | 残差 + 视觉 + 谓词 | servo > replace > abort |
| F4 | 释放过早/掉落 | 夹爪 + 视觉 + 谓词 | regrasp > replace > abort |
| F5 | 插入不足/接触不够 | 残差高 + 进度停滞 | backoff+wiggle > reinsert > abort |
| F6 | 假完成 | 谓词/视觉不一致 | verify > redo > abort |
| F7 | 接触失稳/力不匹配 | 残差方差高 + ACC 低 | slow/reduce gain > reapproach > abort |
| F8 | 外部干扰/undo | 视觉变化 + 模式反转 | redo affected step > replan |
| F9 | 策略 OOD/不确定 | entropy/LLMD/ACC | conservative fallback > reanchor |

#### 4.4.3 恢复库

| 动作 | 参数 | 前置 | 代价 | 风险 |
|---|---|---|---|---|
| `slow` | 速度×0.5，A×1.5 | F7 | 1–2s | 低 |
| `backoff` | 沿接近轴 -5~-20mm | F2/F5 | 1–2s | 低 |
| `wiggle` | 螺旋/锯齿 ±2–5mm，1–3 周期 | F5 | 2–5s | 中（可能扩大接触） |
| `servo` | 腕相机重估位姿，±5mm/±5° 修正 | F3 | 2–4s | 中 |
| `regrasp` | 张开→后退→重闭 | F4 | 3–6s | 中 |
| `replace` | 抬起→重瞄准→再放 | F3/F4 | 5–10s | 高 |
| `reanchor` | 重新检测目标/槽位 | F1/F8 | 2–5s | 中 |
| `redo` | 重做上一步 | F6/F8 | 3–10s | 中 |
| `abort` | 跳过/结束 | 预算 | 0 | 高（丢分） |

#### 4.4.4 代价感知选择

```text
a* = argmax_a [ P(success | F, a, card) - λ·time(a) - μ·risk(a) ]
s.t.  don't undo completed steps unless F6/F8
      attempts_per_step ≤ 2
      elapsed + time(a) < 180s
```

- `P(success|F,a,card)` 先验来自调试槽/合成扰动；没有数据时用保守默认（regrasp > replace > abort）。
- `λ` 按剩余时间调：前 2/3 时间鼓励恢复，后 1/3 只做低成本动作。
- `μ` 按安全风险调：靠近人/易碎物时提高。

#### 4.4.5 Conformal 阈值（无失败数据）

对每个模式/任务，收集成功演示的异常分数 `s_i`（残差 surprise、ACC、entropy 的融合分数），取有限样本分位：

```text
τ = s_(⌈(n+1)(1-α)⌉)
```

在可交换性假设下，`P(s_test ≤ τ) ≥ 1-α`。`α=0.05` 或 `0.1`；样本少时跨任务池化，报告每任务 FPR。阈值不是「拍脑袋」，而是有覆盖保证的误报控制。

#### 4.4.6 伪代码

```python
def diagnose(obs, r_f, m, card, state):
    ev = {
        "residual": zscore(r_f, card.mode(m).residual),
        "acc": 1 - cosine(state.prev_chunk, state.cur_chunk),
        "entropy": action_entropy(state.cur_chunk),
        "gripper": zscore(obs.g, card.mode(m).gripper),
        "progress": state.ssg.progress(obs),
        "visual": visual_change(obs, state.last_visual),
        "time": state.elapsed / card.budget_s,
        "mode": -logprob(state.mode_history, card),
    }
    surprise = fuse(ev, card.weights)
    if surprise <= card.tau[m]:
        return None
    fault = argmax_f P(f | ev, card.failure_prior)
    action = argmax_a [P(success | fault, a, card)
                       - LAMBDA * cost(a) - MU * risk(a)]
    return fault, action
```

### 4.5 接口与集成

- **动作空间**：优先 `ee`；若底座只能 `joint`，用 FK/IK 把 `Δx` 映射到关节增量（`Δq ≈ J^+ Δx`），或只做诊断不做柔顺。
- **chunk**：推荐 1–2；回退 4。`meta.token`、dtype/shape 严格按 README；不要返回异常值/NaN。
- **观测**：只声明需要的键；EE pose + 夹爪 + 两路腕部相机是 SCC/Dx 的最小集；高位相机给 VLA。
- **延迟**：VLA 缓存 + SCC 轻量；p99 稳定优先；不要在接触段做重推理。
- **单模型**：VLA 是唯一学习模型；TPC/SCC/Dx 在模型卡里披露为「确定性运行时层 + 离线统计表」。
- **回退开关**：`scc=off`、`dx=off`、`chunk=4` 三个开关；任何异常都能退回基线。

## 5. 标定协议

### 5.1 离线（无机器人）

1. 对 32 个数据集（或先 8 个）提特征：残差、夹爪、速度、相位、ACC（需要 chunk 重叠；演示没有 chunk，可用滑窗动作差代替）。
2. 每个任务/臂/模式拟合自由空间基线 `ê(v)`；统计残差分布；算 AUROC/FPR/TPR。
3. 用成功演示做 conformal 阈值；用任务留一交叉验证检查跨任务泛化。
4. 生成 32 张 JSON 卡；人工审计 8–10 张（模式顺序、夹爪状态、干扰剧本）。
5. 产出「残差可检测性表」：哪些任务/阶段强、哪些弱；弱信号任务不启用 SCC。

### 5.2 调试槽（真机机制验证）

候选：T10 PlugCharger（插入，强信号）、T27 StackBowls（叠放，放置）、T19 ZipUp（deformable/undo）、T26 InsertTube（插入，若可用）。

- A/B：E0（固定 chunk/增益）vs E4（PACT）；同任务、同初始条件，3–5 trials each（机制验证，不做统计推断）。
- 记录：终局成功、总成功、步骤分、时间、恢复次数、碰撞/掉落、延迟。
- 判定：E4 终局 +≥10pp 且时间 +≤20% → 继续；否则回退/只保留 Dx。
- 安全：先空载/低速；Δx 限幅；急停条件（残差超安全阈值、EE 无效、超时）。

### 5.3 恢复库标定

- 用合成扰动（物体平移/旋转/移除）在仿真或调试槽测每个恢复动作的成功率/耗时。
- 没有失败数据时，先验用保守默认；每次调试槽后更新。
- 记录「恢复反效果」：例如 replace 把已成功的步骤弄坏；加「不做坏」约束。

### 5.4 失败数据问题

- 官方只有成功演示；我们不自造大规模失败数据（贵且偏）。
- 诊断阈值用成功演示 + conformal（FIPER/VLA-FAIL 路线）。
- 故障分类的先验来自官方人类干扰剧本 + 调试槽少量失败；没有数据时用规则/保守先验。
- 局限：conformal 保证是边际的，不是每任务；且可交换性可能被 OOD 轴（位置/背景/未见物体/人类干扰）破坏。按条件分层/报告每任务 FPR，避免「平均 5% 但某任务 30%」。

## 6. 实验矩阵

### 6.1 主实验

| 编号 | 系统 | 目的 |
|---|---|---|
| E0 | 基线 VLA + 固定 chunk 8 + 固定增益 | 对照 |
| E1 | chunk 1–2 + 固定增益 | 隔离「逐步反馈/延迟」效应 |
| E2 | SCC 全局增益（无画像） | 残差柔顺是否有效 |
| E3 | TPC 画像增益（无诊断） | 画像条件化是否有效 |
| E4 | PACT = TPC + SCC + Dx | 主系统 |
| E5 | E4 + CMV/HMM（研究版） | 模式词表是否抗 OOD |

### 6.2 消融

- 去掉残差（只用夹爪/相位）
- 去掉相位（全局阈值）
- 去掉 conformal（固定阈值）
- 去掉代价感知（固定恢复顺序）
- 去掉 PACE/低速过渡（固定 H）
- 去掉模式后验（硬分类）
- 只用 Dx 不柔顺（诊断但不改动作）

### 6.3 指标

- 主：平均成功率、平均步骤分、终局步成功率、接触段成功率。
- 诊断：AUROC、TPR@5%FPR、每任务 FPR、检测时延、恢复成功率、恢复反效果率。
- 工程：每 episode 时间、p50/p99 延迟、动作平滑度、碰撞/掉落、超时。
- 画像：覆盖率（多少任务有卡）、模式分割可解释性、跨任务留一表现。

### 6.4 Go/No-Go

| 里程碑 | 条件 | 不过怎么办 |
|---|---|---|
| M1 离线 | 插入 AUROC ≥0.85；轻物体融合 AUROC ≥0.75 | 只对强信号任务开 SCC |
| M2 调试槽 | E4 终局 +≥10pp；时间 +≤20%；无安全违规 | 回退 E3/E2 |
| M3 计分跑 | 目标 +5pp；+3pp 只作方向性证据（需任务配对 CI 支持；320 trials 下 +3pp 通常 CI 跨 0） | 保留 Dx，砍 SCC |
| M4 最终 | 稳定、可回退、模型卡完整 | 提交基线+安全层 |

### 6.5 统计分析

- 预注册主指标：平均成功率；次指标：步骤分、终局成功率。
- 任务配对 bootstrap（32 任务 × 10 trials）；报告 95% CI。
- 不把占位榜 29.7% 当基线；用 E0 同条件对照。
- 单次计分跑只当「机制验证」，不当「统计证明」。

### 7.1 新增点的差异（相对最接近的工作）

- **vs HumanoidVLM**：它是任务级 VLM-RAG 检索固定 K/D，9 任务、4090 外挂；我们是相位/模式级、32 任务、运行时无 VLM、带诊断/恢复。它证明了可行性，我们做闭环与规模。
- **vs PACE**：它只改执行 horizon，不管接触/诊断；我们把相位执行与残差柔顺、诊断耦合，并解决 UniBot chunk 整段执行的接口约束。
- **vs VLA-FAIL/FIPER**：它们只检测失败，不控制、不恢复、不用接触残差；我们把控制级残差与任务画像接进证据图，并输出代价感知恢复。
- **vs CompVLA/URF/TAO-Force**：它们学习柔顺或需要力反馈；我们训练免费、无力传感、模型无关，适合「单模型 + 位置 API」的比赛约束。
- **vs 头部模型**：不竞争底座，做正交的运行时层；底座越强，PACT 越值钱（因为它补的是接触/诊断）。

### 7.2 已砍清单（跨轮）

- VLM-RAG 在线每 episode 检索（慢、9 任务规模、4090 外挂）
- 力/力矩传感器假设（API 没有）
- 学习式柔顺/第二个策略网络（单模型风险）
- 全 32 任务高保真孪生；自由仿真数据；运行时 MPC；仿真 RL；布料/拉链/透明全物理
- 每任务 LoRA/模型合并；世界模型作为主路径
- 用占位榜 29.7% 做基线/上限
