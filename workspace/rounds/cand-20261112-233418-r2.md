# 第 2 轮迭代 · 支线 C（灵感循环 v2c：「迁移学习」×「惯性测量单元」）—— 从「视觉事后核验」到「可迁移的本体感知事件语法」

> 承接 v2（UIP-01′~15：Gazebo 计分神谕 × 实时性 × 模块化）。本轮不新增传感器、不新增外部模型，只把两个灵感词读成接口约束下的两个硬问题：
> - **惯性测量单元**：提交接口的观测目录里**没有 IMU / gyro / accel / quaternion 键**。可用的只有 4 路图像、双臂 7 维关节、双手 6 维 ee pose、两个夹爪开度、15 维下半身关节、语言。于是问题不是“如何用 IMU”，而是“**在没有 IMU 的接口里，能否重构一个足够好的 vIMU（virtual IMU），以及它到底能看见哪类扰动**”。
> - **迁移学习**：32 个任务、32 个数据集、sim→real、单模型。问题不是“再训一个模型”，而是“**哪些知识可以跨任务/跨域迁移，哪些会负迁移，如何在部署时门控**”。
>
> 本轮的核心结论：**人为撤回不是一个检测问题，而是三个可观测性问题**——B 类（身体耦合）、C 类（接触耦合）、F 类（自由物体）。vIMU 只能覆盖 B/C，F 类必须交给视觉；迁移学习真正该迁移的不是像素策略，而是**事件语法**；而事件语法的前提是先把观测性分类做对。

## 0. 承接、核实与修正（v2 → v2c）

| 事实 | 内容 | 对本轮的含义 |
|---|---|---|
| 观测目录（README §2） | 4 图 + `left/right_arm[7]` + `left/right_ee_pose_gripper_base[6]` + `left/right_gripper[1]` + `lower_body[15]` + `language`；**无 IMU / gyro / accel / quaternion 键** | 不能直接读 IMU；只能从关节/ee 轨迹数值微分出 vIMU |
| 数据集字段（HF `meta/info.json`） | `lower_body[15]` 的字段名是 12 个腿关节 + 3 个腰关节，是**关节位置**，不是 IMU | vIMU 的“身体耦合”分支只能算**间接代理**，不是真惯性测量 |
| `obs_delta_indices` | 键决定发送哪些观测；值决定时间堆叠；偏移 ≤0、严格递增；不足补首帧 | 可以把 30 帧本体感觉一次要回来，代价极小（见 §3.3） |
| 动作块（README §3） | 每个动作数组形状 `(T_a, …)`，`T_a = action_chunk_size`；索引 0 先执行 | **不能默认“每次可返回更短的块”**；v2 的 ACS 若依赖变长块，是把未核实假设当成事实 |
| `human_*` 撤回（v2 §0 继承） | T12 拿走锁、T14 拧回、T16 翻开、T17 打开、T19 拉开、T27 拿下第二个…… | 撤回的**物理耦合方式不同**，不能用同一个检测器 |
| 计分 | 平均成功率 + 步骤分；末步分值 ≥ 前序步 | 漏检撤回 = 直接丢步骤分；误检 = 浪费动作/延迟 |

**本轮对 v2 的两处修正**：

1. **不再把“变长动作块”当作反应性来源。** README §3 要求动作形状与 `T_a` 一致；在确认评测端允许变长块之前，应默认 `T_a` 固定。反应性改由“固定块 + 稠密本体历史 + 块边界回看”实现。
2. **不再把 `human_*` 当作单一扰动轴。** 先把撤回按可观测性分成 B/C/F，再决定用 vIMU 还是视觉；否则会造一个“看起来在检测、实际上看不见”的检测器。

## 1. 上轮诊断（v2 的四个盲区）

- **G1 检测器单一化**：v2 的 `regressed` 是一个二值状态，隐含“所有撤回都能被同一个验证器看见”。但 T11/T25 是底座被移动（身体耦合），T14/T19 是接触中的反向操作（接触耦合），T16/T27 是自由物体被拿走（无本体信号）。
- **G2 视觉采样率与延迟**：开环动作块 + JPEG 传输 + 验证器推理，使视觉核验的“事件时间分辨率”大约是块长量级；快速撤回可能在两次核验之间发生，并被“看见得太晚”。
- **G3 迁移未量化**：v2 的 Gazebo/DRF 造数据隐含“仿真扰动可以迁移到真机”，但没有定义迁移的**域差距**、**负迁移**与**门控**；这正是 v2 自述的最大风险（用仿真过拟合仿真）。
- **G4 没有时间信用分配**：v2 只重做“当前子目标”；如果撤回发生在块内、且块内已经推进了多个子目标，“当前”未必是“被撤回”的那个。

## 2. 两个词的直觉与严谨定义

### 2.1 惯性测量单元：先给直觉

IMU 的价值不是“多一个传感器”，而是**高频率、低延迟、低带宽地感知“力/运动的事件”**：接触开始/结束、打滑、被推、被拧、被拉。对桌面操作，这些事件往往比“物体长什么样”更接近“刚刚发生了什么”。但接口没有 IMU，所以我们要做的不是“接入 IMU”，而是**从已有的关节/ee 轨迹里重构一个 vIMU**，并诚实回答：它看得见什么、看不见什么。

**定义 2.1（vIMU）**：设第 t 帧可用本体感觉为

`p_t = (q_t^L, q_t^R, x_t^L, x_t^R, g_t^L, g_t^R, q_t^body) ∈ R^43`。

用 `obs_delta_indices` 取回窗口 `P_t = (p_{t−m}, …, p_t)`，定义

```
q̇_t ≈ (q_t − q_{t−1}) / Δt,     q̈_t ≈ (q_t − 2q_{t−1} + q_{t−2}) / Δt²
ξ_t  = log(T_{t−1}^{−1} T_t) / Δt          # ee 的 SE(3) twist
r_t  = q̈_t − q̈_t^cmd   或   r_t = ξ̇_t − ξ̇_t^cmd
```

`r_t` 是**命令-实际残差**（控制里的 disturbance observer 思路）。vIMU 的输出不是加速度本身，而是 `(‖r_t‖_Σ, r_t/‖r_t‖, 哪些关节/哪一侧)` 这个**事件签名**。

**命题 2.1（自由物体撤回的本体不可观测性）**：若扰动只移动一个与机器人无接触的自由物体，且底座固定，则可用本体感觉 `P_{0:T}` 与扰动事件 e 在统计上独立，即 `I(e; P_{0:T}) = 0`。因此任何仅依赖 vIMU 的检测器对 F 类事件的召回率不可能高于随机。

*证明直觉*：无接触 ⇒ 关节/ee 轨迹的生成过程不变 ⇒ 本体观测分布不变。证毕。

这条命题不是学究气：它直接解释了为什么 v2 的“统一 regressed 检测器”会在 T16/T27 这类任务上失效，也决定了本轮必须做**传感器路由**而不是“更强的 vIMU”。

**命题 2.2（带宽套利）**：本体感觉每帧 43 个 float32 = 172 B；30 帧 ≈ 5.16 KB。单张 480×640×3 原始图 = 921.6 KB；即使按 JPEG 压缩到约 100 KB，30 帧本体仍只占其约 5%。因此“把本体历史堆到 30 帧”是用**个位数百分比**的载荷，换取一个数量级更高的时间分辨率。

*含义*：在 `obs_delta_indices` 里给状态键堆 30 帧、给图像键只留 `[0]` 或 `[-1,0]`，是比“多发几帧图像”更划算的实时性投资。

### 2.2 迁移学习：先给直觉

迁移学习不是“把在 A 上训的模型直接拿去 B 用”，而是**判断哪些结构在 A 和 B 之间不变，只搬那些不变的东西**。在本题里，像素、背景、物体身份都会变（`unseen_object_*`、背景、位置），但“被拧回去”“被拉上再拉开”“被拿走”这些**事件的动力学语法**在 32 个任务里高度重复。所以应该迁移的是**事件语法**，不是像素策略；而事件语法的可迁移性，取决于源域和目标域在事件空间里的差距，以及标签语义是否冲突。

**定义 2.2（迁移问题）**：源域 `D_S = {(o, a, e)}`（仿真/Gazebo/有扰动标注的任务），目标域 `D_T = {(o, a)}`（真机/无扰动标注的任务）。共享编码器 `E_θ`，任务适配器 `a_τ`，事件头 `h_e`。目标：

```
min_θ  ε_T(π_θ)   s.t.  ε_T ≤ ε_S + ½ d_HΔH(D_S, D_T) + λ
```

其中 `d_HΔH` 是域间散度，`λ = min_h [ε_S(h)+ε_T(h)]` 是理想联合误差。**迁移只在 `d` 小且 `λ` 小的时候安全**；否则负迁移。

**定义 2.3（事件空间迁移门槛）**：用事件签名 `z^e = E_e(r_{t−w:t})` 代替像素特征，定义

```
d_E = MMD(z^e_S, z^e_T),     λ̂ = 源/目标事件头的预测分歧（无标签代理）
gate = 1[ d_E ≤ τ_d  ∧  λ̂ ≤ τ_λ ]
```

`gate=1` 才允许把源域的事件先验搬过来；否则退回“通用事件头 + 视觉兜底”。

**为什么事件空间比像素空间更适合迁移**：事件签名是物理量（加速度/力矩方向、接触时序、关节残差），对背景、颜色、物体身份不敏感；像素特征则会被 `unseen_object_*` 和背景变化直接推离源域。这是本轮把“迁移学习”落到实处的关键。

### 2.3 合流：可观测性路由 + 事件语法 + 迁移门控

三句话：

1. **观测性分类**决定“该信哪个传感器”（B/C → vIMU，F → 视觉）。
2. **事件语法**决定“迁移什么”（任务无关的接触/撤回/滑动原语，而不是像素）。
3. **迁移门控**决定“什么时候不迁移”（`d_E` 或 `λ̂` 超阈值就退回通用头）。

## 3. 关键推导

### 3.1 三类扰动与可观测性

| 类 | 定义 | 典型任务（从 v2 的 `human_*` 文本推断） | vIMU | 视觉 |
|---|---|---|---|---|
| **B** 身体耦合 | 人移动/推机器人底座或手臂 | T11 抓前动底座；T25 放第一个后挪底座 | 强（但 `lower_body` 只是代理） | 中 |
| **C** 接触耦合 | 人反向操作机器人正在接触的物体/机构 | T10 拔插头；T12 拿走锁；T14 拧回；T17 合上再打开；T19 拉上再拉开；T26 移插口；T31 拉链；T32 针管 | 中（残差） | 中 |
| **F** 自由物体 | 人移动与机器人无接触的物体 | T16 翻开毛巾；T27 拿走第二个碗；T24 放回传送带起点；T08 挪架子；多数“物体前/后/左/右移” | **≈0** | 强 |

> **重要限定**：上表是从 `human_*` 文本推断的**工作假设**，不是视频核实的事实；“拿走锁/拔插头”是否仍处于接触，取决于具体时刻。E109a 的第一件事就是用公开视频给这些事件打 B/C/F 标签并测一致性。

### 3.2 检测延迟与信用分配

设事件发生在 `t_e`，vIMU 的 CUSUM/GLR 检测器在 `t_d` 触发：

```
S_t = max(0, S_{t−1} + ‖r_t‖_Σ − μ_0 − ν),    t_d = inf{ t : S_t > h }
```

`τ_d = t_d − t_e`。视觉验证器每 `k` 步看一次、且有 `L` 步链路/推理延迟，故 `τ_d^vis ≈ U(0,k) + L`（均匀采样近似）。以 `k=8, L=2` 为例，视觉的中位延迟约 9 步（合成实验 §4），而 B 类 vIMU 可到 0–1 步、C 类约 2–4 步。

**信用分配**：块内可能推进多个子目标。设块边界观察到事件，若只有当前帧，受影响的子目标 `G` 的后验近似在“块内所有子目标”上均匀，熵 `H(G) ≈ log m`；若有稠密历史，事件时刻 `t_e` 可定位到 1 个控制步，`G` 由谓词在 `t_e` 前后的翻转确定，熵降到 `≈0`。这就是“重做正确子目标”与“重做当前子目标”的差别。

### 3.3 载荷算术（可复核）

```
本体/帧 = 7+7+6+6+1+1+15 = 43 floats = 172 B
30 帧本体 = 5,160 B
单张原始图 = 480×640×3 = 921,600 B  ⇒ 30 帧本体 ≈ 0.56% 单张原始图
若 JPEG ≈ 100 KB/张 ⇒ 30 帧本体 ≈ 5.2% 单张 JPEG
```

结论：**稠密本体历史几乎免费**；真正的载荷瓶颈仍是图像。把 `obs_delta_indices` 的图像键压到 `[0]`、状态键堆 30 帧，是“用免费的时间分辨率换昂贵的空间分辨率”。

## 4. 合成实验（仅用于排序杠杆，不是真机证据）

脚本 `tmp/v2c_event_sim.py`，结果 `tmp/v2c_event_sim.json`。假设 30 Hz、视觉每 8 步采样 + 2 步延迟、撤回持续 10 步且不自动恢复；B/C/F 的 vIMU 残差幅度分别为 1.0/0.5/0（加噪声）；每格 3000 episodes。检测窗口 25 步。

| 策略 | B 延迟（中位/p90） | C 延迟 | F 延迟 | 召回 |
|---|---|---|---|---|
| 仅视觉 | 9 / 12 | 9 / 12 | 9 / 12 | 1.00 / 1.00 / 1.00 |
| 仅 vIMU | 0 / 0 | 2 / 4 | **从不** | 1.00 / 0.85 / 0.00 |
| 路由（无兜底） | 0 / 0 | 2 / 4 | 9 / 12 | 1.00 / 0.85 / 1.00 |
| **路由 + 视觉兜底** | **0 / 0** | **3 / 7** | **9 / 12** | **1.00 / 1.00 / 1.00** |

**读法**：

1. vIMU 在 B 类几乎零延迟，在 C 类显著快于视觉，但对 F 类**完全失明**（与命题 2.1 一致）。
2. 没有一种传感器单独占优；**路由 + 兜底**才同时拿到“快”和“全”。
3. C 类的召回/延迟对残差阈值敏感（本实验 0.85 → 兜底后 1.00）；真机上必须用 GSO 接触标签标定，不能照搬这里的数字。

## 5. 候选合并 → v2c 清单

围绕两词发散 10 个草案，合并为：**旗舰 UIP-01″（RHPV-DI）**，由 **UIP-16 vIMU** 提供高频事件、**UIP-17 DOT/DEG** 做可观测性分类与事件语法、**UIP-18 XTG** 做迁移门控、**UIP-19 EVT** 迁移验证器、**UIP-20 ITR** 做时间信用分配；v2 的 02′/09′/11/12/13/14/15 相应升级。详见产物区。

## 6. 瓶颈假设（更新）

- **H1（最高杠杆）**：撤回的**可观测性分类**比检测器本身更重要；把 F 类误判为 C 类会让系统在最关键的任务上静默失效。
- **H2**：vIMU 是“事件时间分辨率”的廉价来源，但不能替代视觉；正确用法是**路由**，不是“更强的单传感器”。
- **H3**：迁移应发生在**事件空间**而非像素空间；`d_E`/`λ̂` 门控可以避免负迁移，但门控本身需要目标域的无标签校准。
- **H4**：固定 `T_a` + 稠密历史 + 块边界回看，是在 README §3 约束下实现反应性的稳妥路径；变长块只能作为“确认允许后”的优化。
- **H5**：时间信用分配（重做被撤回的那个子目标）比“重做当前子目标”更省动作，但依赖事件时刻定位与谓词历史的准确性。

## 7. 本轮最大风险

**一句话**：把“人为撤回”当成一个统一的可检测事件，而实际上占多数的自由物体撤回（T16 翻开毛巾、T27 拿走碗、T24 放回货物）在本体感知上信息为零；一旦 B/C/F 分类错配，vIMU + 迁移的事件路由会在最关键的干扰上静默失效。

**→ 本轮最值得押注：UIP-17（可观测性分类/事件语法）× UIP-16（vIMU）× UIP-18（迁移门控）组成的“路由式事件感知”**——它不违反“无 IMU 接口、单模型、固定动作块”三条硬约束，且把 v2 最大的两个风险（视觉核验太慢、仿真过拟合）同时变成可度量的工程问题。

## 1. 旗舰深潜：UIP-01″ · RHPV-DI（Routing-aware Progress Verification with Disturbance and Inertial events）

**机制**：每个 `get_action` 边界做四件事：

1. **取稠密历史**：`obs_delta_indices` 对状态键堆 30 帧（≈1 s @30 Hz），图像只留当前帧。
2. **vIMU 事件检测**：由关节/ee 轨迹的二阶差分与命令残差 `r_t` 计算 CUSUM/GLR 统计量；若超过阈值，输出事件 `(t_e, signature, class)`。
3. **可观测性路由**：
   - `B`（身体耦合）或 `C`（接触耦合）→ 信任 vIMU，立即进入重做/核验；
   - `F`（自由物体）→ vIMU 无信号，交给视觉验证器；若视觉也未见，保持原计划但在“离开高价值自由物体”前增加一次目视确认。
4. **时间信用分配**：用 `t_e` 回放谓词历史，找到在 `t_e` 前后从 `done` 翻回 `undone` 的子目标 `g_i`，只重做 `g_i`；而不是盲目重做“当前子目标”。

**接口适配（关键）**：

```python
STACK = list(range(-29, 1))          # 30 frames, strictly increasing, all <= 0
metadata = {
    "control_space": "joint",
    "obs_delta_indices": {
        "observation.language": [0],
        "observation.images.cam_left_high": [0],
        "observation.images.cam_right_high": [0],
        "observation.images.cam_left_wrist": [0],
        "observation.images.cam_right_wrist": [0],
        "observation.state.left_arm": STACK,
        "observation.state.right_arm": STACK,
        "observation.state.left_ee_pose_gripper_base": STACK,
        "observation.state.right_ee_pose_gripper_base": STACK,
        "observation.state.left_gripper": STACK,
        "observation.state.right_gripper": STACK,
        "observation.state.lower_body": STACK,
    },
    "image_resize": {                # optional: cut image payload, keep wrist native
        "observation.images.cam_left_high": [240, 320],
        "observation.images.cam_right_high": [240, 320],
    },
    "action_chunk_size": 8,          # fixed T_a; do not assume variable-length chunks
    "token": token,

```

**与 v2 的差异**：

- v2 用“每 k 步视觉核验 + 重做当前子目标”；v2c 用“vIMU 事件 + 路由 + 重做被撤回子目标”。
- v2 的 `regressed` 是单轴；v2c 把它拆成 B/C/F，并显式承认 F 类只能靠视觉。
- v2 的 ACS 假设可返回更短块；v2c 修正为固定 `T_a`，把反应性放到“历史回看 + 块边界”上。

**风险**：B/C 分类错误会导致错误重做；用 UIP-15′ 的护栏（置信度门限、最大重做次数、延迟预算）和“F 类不触发 vIMU 重做”的硬规则兜底。

## 2. UIP-16 · vIMU（Virtual Inertial Measurement Unit）

**输入**：`p_t = (q_t^L, q_t^R, x_t^L, x_t^R, g_t^L, g_t^R, q_t^body) ∈ R^43`，来自接口已有观测。

**计算**：

```
q̇_t  = SavitzkyGolay(P_t.q, window=5, poly=2, deriv=1) / Δt
q̈_t  = SavitzkyGolay(P_t.q, window=5, poly=2, deriv=2) / Δt²
ξ_t   = log(T_{t−1}^{−1} T_t) / Δt
r_t   = [q̈_t − q̈_t^cmd, ξ̇_t − ξ̇_t^cmd]        # command-vs-actual residual
z_t   = (‖r_t‖_Σ, r_t/‖r_t‖, segment_mask)       # event signature
```

- **命令项**来自上一个动作块（joint 模式用关节目标，ee 模式用位姿目标）；若控制空间为 ee，则用逆运动学或直接比较 ee twist。
- **归一化**：按关节限位/噪声 MAD 标准化；每个机器人单独标定 `μ_0, ν, h`。
- **事件统计量**：`S_t = max(0, S_{t−1} + ‖r_t‖_Σ − μ_0 − ν)`；`S_t > h` 触发。
- **签名分类**：`lower_body/waist` 残差占优 → B；`arm/ee` 残差在接触门控下占优 → C；无显著残差 → F（并立刻交给视觉）。

**限制（必须写进论文/答辩）**：

1. 这不是真 IMU；`lower_body` 是关节位置，底座平移**不直接可观测**，B 类只是“代理可观测”。
2. F 类事件与本体轨迹独立（命题 2.1），vIMU 的召回率为随机；不得声称“vIMU 覆盖所有撤回”。
3. 二阶差分对噪声敏感；必须平滑、限幅，并用 `T_a` 与 `Δt` 校准。

## 3. UIP-17 · DOT/DEG（Disturbance Observability Taxonomy + Disturbance Event Grammar）

### 3.1 可观测性分类（工作假设）

> 完整 32 任务计分表沿用 v2 §2；这里只标注与撤回/接触有关的任务。`C/F` 表示“取决于事件发生时是否仍接触”，需视频核实。

| 类 | 任务 | 依据（v2 的 `human_*` 文本） |
|---|---|---|
| **B** | T11、T25 | 抓前动底座；放第一个后马上挪底座 |
| **C** | T10、T12、T14、T17、T19、T26、T31、T32 | 拔插头；拿走锁；拧回；合上再打开；拉上再拉开；移插口；拉链；针管抽/注 |
| **C/F** | T05、T08、T10、T11、T12、T17、T26 | 另一头也插上；抓书后挪架子；抓前移动/拔起插头；动底座/动绿盒；锁移动/拿走；合上/打开；移网线/移插口 |
| **F** | T16、T27、T24、T01–T04、T06、T07、T09、T13、T15、T18、T20–T23、T28–T30 | 翻开毛巾；拿走第二个碗；放回传送带起点；多数“物体前/后/左/右移” |

### 3.2 事件语法（可迁移的原语）

```
V = { contact_onset, contact_loss, slip, twist_reverse, pull_reverse,
      base_push, free_object_move, zip_reverse, pour_reverse }
```

每个事件 `e = (class, t_e, signature, affected_subgoal)`。事件语法是**任务无关**的：同一个 `twist_reverse` 既可用于拧药瓶（T14），也可用于开锁（T12）；同一个 `zip_reverse` 可用于 T19/T31。UIP-18/19 迁移的就是这套语法，而不是 32 个任务的像素策略。

### 3.3 标注协议（E109a）

1. 从公开数据集中抽取含 `human_*` 的 episode 与正常 episode；
2. 两名标注者独立给事件打 `B/C/F` 与事件原语标签；
3. 计算 Cohen's κ；κ < 0.7 的类别不进入训练，只做“待定”；
4. 用 GSO（UIP-11′）生成接触/力矩真值，校验人工标签。

## 4. UIP-18 · XTG（Cross-task/Cross-domain Transfer Gate）

**目标**：把源域（Gazebo/DRF/有扰动标注任务）的事件先验迁移到目标域（真机/无标注任务），并显式拒绝负迁移。

**形式化**：对假设 `h`，

```
ε_T(h) ≤ ε_S(h) + ½ d_HΔH(D_S, D_T) + λ
```

在**事件空间**中计算 `d_E = MMD(z^e_S, z^e_T)`，用源/目标事件头的预测分歧估计 `λ̂`（无标签代理）。门控：

```
gate = 1[ d_E ≤ τ_d  ∧  λ̂ ≤ τ_λ ]
```

**部署算法**：

```python
def select_event_head(z_e_target, src_protos, head_s, head_t, tau_d, tau_l):
    d = mmd(z_e_target, src_protos)
    l = disagreement(head_s(z_e_target), head_t(z_e_target))
    if d <= tau_d and l <= tau_l:
        return head_s              # transfer source event prior
    return head_generic           # fallback: generic head + vision
```

**负迁移监控**：在目标域上用无标签指标（事件头熵、vIMU 残差重构误差、视觉验证器一致性）持续监控；若连续 N 次超过基线，关闭源域先验，退回通用头。

**源域从哪来**：

- UIP-12′ 的 Gazebo 三类扰动（B/C/F）与随机化耦合；
- 有 `human_*` 文本但无视频的任务，先用文本生成“事件原语”弱标签；
- 有视频的任务，用 E109a 的人工标签做小规模校准。

## 5. UIP-19 · EVT（Event-grounded Verifier Transfer）

**问题**：v2 计划为 32 个任务各写验证器，工程量大且难以迁移。

**机制**：训练一个共享的事件接地验证器

```
V_θ(z^e_t, z^v_t, g) → {done, ongoing, regressed, fail}
```

- `z^e`：vIMU 事件签名（UIP-16/17）；
- `z^v`：共享视觉-语言编码（主骨干）；
- `g`：当前子目标/计分步。

**迁移方式**：

1. 在 UIP-11′ GSO 有几何真值的任务上预训练 `V_θ`；
2. 在有人工 B/C/F 标签的任务上微调事件头；
3. 对没有标签的任务，只训练一个低秩任务适配器 `a_τ`（共享骨干不变）；
4. 保留**几何谓词兜底**：若 `V_θ` 置信度低，退回可解释的几何判据。

**收益**：把“32 个手工验证器”压缩为“1 个共享验证器 + 少量任务适配器 + 几何兜底”，同时天然满足单模型合规（共享一条骨干）。

## 6. UIP-20 · ITR（Inertial-Temporal Rewind）

**机制**：维护事件时间线 `T = [(t_e, class, signature, g_i)]`。当在块边界检测到事件：

1. 用 `t_e` 在稠密历史中定位事件发生的那一步；
2. 回放（或查询）各子目标的谓词 `V_i(t)`，找到在 `t_e` 前后从 `done` 翻回 `undone` 的 `g_i`；
3. 只重做 `g_i`，而不是重做当前子目标 `g_now`；
4. 若 `g_i` 之后还有已完成的子目标被连带破坏（例如叠碗时拿走下面的碗），按依赖图级联重做。

**与 v2 的差异**：v2 的 `regressed` 只触发“重做当前”；v2c 用历史把“当前”与“被撤回”分开。这是“稠密本体历史”最直接的收益。

**风险**：谓词历史回放需要廉价验证器；若验证器本身昂贵，退化为“只回看事件签名 + 依赖图”，不逐帧调用大模型。

## 7. 升级项与两处修正

- **UIP-02′ SSG**：计分账本增加 `(observability_class, redo_cost, exposure_window)`；对 F 类高权重步骤，优先“完成前目视确认/完成后短暂停留观察”，而不是盲目重做。
- **UIP-09″ DCR-R**：从二值 `regressed` 升级为 `B/C/F` 路由；B/C 走 vIMU，F 走视觉；输出事件时间线与受影响子目标。
- **UIP-11′ GSO**：除几何计分谓词外，记录**接触力/关节力矩/真实事件时刻**，为 vIMU 检测器提供真值标签与阈值标定。
- **UIP-12′ DRF**：按 B/C/F 三类生成扰动；随机化耦合强度、时机、速度；专门生成“弱接触/刚释放”的边界样本，防止把 F 类误标为 C 类。
- **UIP-13′ FCS（修正 v2 ACS）**：**不再假设每次可返回更短的块**。在 README §3 的 `(T_a, …)` 约束下，固定 `T_a`；用稠密历史 + 块边界回看实现反应性。若后续确认评测端允许变长块，再把“接触阶段缩短块”作为可选优化。
- **UIP-14′ MSGR**：技能图节点增加事件签名与可观测性标签；路由时用 `language + 首帧 + 事件语法` 选择技能，而不是只靠语言。
- **UIP-15′ CSG**：护栏扩展为“重做次数 + 延迟预算 + vIMU 置信度 + 迁移门控状态”；任何一项越界就退回保守策略（视觉核验 + 通用头）。
- **UIP-08′ LAT-ENG**：保留共享骨干/批处理/每端口隔离；补充“状态键堆 30 帧、图像键只留当前帧”的载荷配置，作为多端口并发的默认。

## 8. 关键伪代码

### 8.1 vIMU 事件检测

```python
def vimu_event(hist, dt=1/30, mu0=0.35, nu=0.05, h=0.35):
    P = hist[-30:]                       # 30-frame proprioceptive window
    qdd = savgol_deriv2(P.q, dt)
    r = qdd - P.qdd_cmd
    s = norm(r)
    S = max(0.0, P.prev_S + s - mu0 - nu)
    if S > h:
        seg = "body" if norm(r.body) > norm(r.arm) else "arm"
        klass = "B" if seg == "body" else ("C" if P.in_contact else "F")
        return Event(t=P.now, klass=klass, sig=r / (s + 1e-9)), S
    return None, S
```

### 8.2 主循环（RHPV-DI）

```python
class RHPVDI:
    def reset(self):
        self.policy.reset(); self.g = 0; self.hist = []
        self.timeline = []; self.S = 0.0; self.redo = 0

    def get_action(self, obs):
        self.hist.append(obs)
        ev, self.S = vimu_event(self.hist)
        if ev is not None and ev.klass in ("B", "C"):
            g_hit = self.credit(ev.t, self.hist)       # UIP-20
            if self.guard.ok(ev, g_hit, self.redo):
                self.redo += 1
                self.timeline.append((ev.t, ev.klass, g_hit))
                return self.redo_chunk(obs, g_hit)     # redo the affected subgoal
        st, conf = self.verifier(obs, self.lang, self.g)
        if conf >= self.thr:
            if st == "regressed":                      # F-class / vision path
                self.g = self.credit_visual(obs)
                return self.redo_chunk(obs, self.g)
            if st == "done":
                self.g += 1
        return self.policy.get_action(obs, self.K)     # fixed T_a = K
```

### 8.3 迁移门控

```python
def event_head(z_e, src_protos, head_s, head_generic, tau_d, tau_l):
    d = mmd(z_e, src_protos)
    l = disagreement(head_s, head_generic, z_e)
    return head_s if (d <= tau_d and l <= tau_l) else head_generic
```

## 10. 合规、风险与资源

**合规**：

- **无新传感器**：vIMU 只用接口已有的 43 维本体感觉；不要求评测端增加 IMU 主题。
- **单模型**：vIMU 是解析计算；事件头/验证器是共享骨干上的小头；不调用外部 VLM/API。
- **固定动作块**：默认 `T_a` 固定；不把“变长块”当作既定能力。
- **F 类诚实**：自由物体撤回在本体感知上不可观测；必须由视觉/验证器兜底，不得宣称 vIMU 全覆盖。

**风险**：

1. **可观测性误分类**：B/C/F 标签目前来自文本推断，未经视频核实；这是本轮最大风险（见 §11）。
2. **vIMU 噪声/标定**：二阶差分放大噪声；不同机器人/负载/温度会改变阈值；需逐机标定与在线自适应。
3. **迁移负效应**：事件空间仍可能有域差距；门控只能降低风险，不能消除。
4. **信用分配错误**：回放谓词可能把“未受影响”的子目标判为被撤回；需依赖图与置信度门限。
5. **延迟**：30 帧本体虽便宜，但解析计算与事件分类仍有开销；必须放进 UIP-15′ 的延迟预算。

**资源与时间线（粗排）**：

- 第 1–2 周：E109a 视频标注；在公开数据上实现 vIMU 与阈值标定。
- 第 3–4 周：GSO 接触/力矩标签；E109/E110；确定 B/C/F 路由规则。
- 第 5–6 周：ITR 时间信用分配；EVT 共享验证器；E111/E113。
- 第 7–8 周：DRF 三类扰动；XTG 迁移门控；E112。
- 第 9 周起：预约真机，用真实步骤分校准 vIMU 阈值与迁移门控。

## 11. 本轮最大风险 & 押注

**一句话**：若把 B/C/F 的文本推断当成已验证事实，整套“vIMU + 事件迁移”会在占多数的 F 类自由物体撤回上静默失效——检测器看起来在工作，实际只覆盖了少数身体/接触耦合事件。

**→ 押注：UIP-17（可观测性分类/事件语法）× UIP-16（vIMU）× UIP-18（迁移门控）**——先用 E109a 把“哪些撤回看得见”钉死，再用事件空间迁移把少量有标签任务的先验搬到其余任务；这比继续堆一个“统一检测器”更诚实，也更接近 v2 最大得分缺口的真实结构。
