# 第 74 轮（承接第 73 轮「MODGAUGE-RAS 计量契约代数」IP-295~302，含追加的 ECG/MIC/IP-302；灵感循环第 1 轮；本轮灵感：「角色一致性」×「能耗优化」）

> R73 把证据变成**可组合的契约**（EC/MMS/CCA/ΣREFLEX/CPB），并追加因果图 ECG 与形态无关契约 MIC。但它默认了两个「无限」：
> - **权威无限（角色缺失）**：契约规定了模块「能产出什么证据」，却没规定「谁有权为这条证据背书」。生产者与审计者可以是同一模块；深度自标定（定义 378）用深度残差更新深度不确定度，R73 用「外部基准」打补丁，但这是**语义补丁**不是**结构禁令**。组合代数能算出 u，却算不出「这条 u 由谁负责」。一旦热替换把审计实现换掉（引理 35 只保证同契约，不保证审计独立），系统可能在**没有任何角色变更记录**的情况下发生权限迁移。
> - **能量无限（资源缺失）**：ΣREFLEX 的 c_reflex 是抽象的交互代价，WCET 是时间预算，但没有一个可测量、可审计、可组合的**能量**预算。真实机器人里，「走近看更清楚」要耗电，「多模态交叉验证」要耗电，「保留审计通道」也要耗电。R73 的 PVOP 只优化 u 与抽象 reflex，会系统性**把电花在能提升精度的证据上，而把审计当作免费品**。
>
> 两个灵感正好是同一枚硬币的两面：
> - **角色一致性** → **RCA（Role Consistency Algebra）**：把「谁产出 / 谁审计 / 谁裁决 / 谁执行 / 谁记账 / 谁主张」变成显式角色类型；职责分离（P⊥A、R⊥C、K⊥受益人、X⊥A）成为 MReg 的**图着色约束**；热替换必须携带**角色转移证书 RTC**，否则新实现只能以最小权限入图。角色一致性把 R73 的「单源不定案」「自标定不自举」从口号变成**不可绕过的类型规则**。
> - **能耗优化** → **EEM（Energy Evidence Metrology）+ EBA（Energy Budget Algebra）**：能量本身成为一种需要计量的证据（六分量：驱动/传感/计算/通信/热/泄漏，各有不确定度与追溯链）；能量预算沿 SER/PAR/VETO 组合，并强制**审计能量地板** `e_audit ≥ ε·e_total`——优化只能在「非审计预算」里省电。
> - 两者合起来 → **DEL（Double-Entry Evidence Ledger）**：每笔证据交易 =（借方：能量/见证，贷方：不确定度下降/主张），复式记账要求**贷方不能由借方自己记**（职责分离），且能量来源可追溯。系统不是「可信」，而是「**账能对上、责能落到人**」。
>
> 核心命题：**R73 问「证据能否组合」，R74 问「组合出来的证据由谁负责、花的是谁的电」**。把 MODGAUGE 升级为 **ECON-GAUGE-RAS**（Energy- and role-CONsistent evidence metrology with GAUGE audits）——**证据会计学**。

## 0. 直觉与动机

### 灵感 1（角色一致性 → 职责分离是审计的结构前提）

直觉：审计之所以有意义，不是因为「有审计报告」，而是因为**报告的人不能同时是被审的人**。R73 的所有模块都同时是「证据生产者」和「自身证书持有者」：DPEM 既产出 u_depth，又引用 SEAL-Depth 证明自己校准得好；深度自标定又用深度残差去更新 u_calib。R73 用「外部基准」「单源不定案」做语义补丁，但结构上仍允许**自证**。角色一致性把这一点显式化：每个模块持有一个角色集合（Producer P / Auditor A / Arbiter R / Executor X / Accountant K / Claimant C），MReg 上有一组**冲突边**，要求同一证据的 P 与 A 不相交、同一命题的 R 与 C 不相交、K 不能为自己受益的账目背书、X 不能为自己的执行证据做最终审计。角色不是标签，是**权限**；组合不能「洗角色」（不能通过串联把一个 P 洗成 A），热替换不能「偷偷升权」（必须有 RTC）。

「角色一致性」还有第二层含义——**身份持久**：在热替换、跨本体迁移、跨轮重部署之后，一个模块的角色不能静默漂移。R73 的 MIC 只保证契约形态无关，不保证角色形态无关；新本体可能把原本由「独立深度计」承担的审计职责，悄悄塞回「执行器内置传感」。因此我们把两层合起来：**(a) 横截面的职责分离** + **(b) 时间轴上的角色持久**。

**直觉的严格化**：角色分配 `ρ: V_M → 2^Role` 是一个图着色；角色一致性 = ρ 满足冲突约束 + 角色沿时间/替换的迁移被显式证书覆盖 + 组合不引入新角色。

### 灵感 2（能耗优化 → 能量是第三种预算，且它必须被计量）

直觉：机器人不是「先有证据、再考虑功耗」；**证据本身就是用电买来的**。走近一点（驱动+传感）、多拍一帧（曝光+计算）、多模态交叉验证（通信+审计）、保留审计日志（存储+计算）都要电。R73 有 c_reflex（抽象代价）和 WCET（时间），但没有焦耳。更糟的是，能量估计本身有误差（SOC 模型、温度、内阻、再生制动、采样积分），所以「能耗优化」如果用一个未经审计的能量模型，就会**优化一个错的目标**。

于是能量必须先成为**证据**：EEM 把 e_total 分解为六分量，每分量带不确定度与追溯链；EBA 把能量沿组合代数传播；E-PVOP 最大化「单位焦耳的不确定度下降」，但分母里的审计能量**不可省**。这与 R73 的 DPEM 完全同构：DPEM 说「深度不确定度不是场景不确定度」，EEM 说「能耗估计不是真实能耗」——二者都是把物理量拆成有追溯链的分量，而不是给一个标量。

**直觉的严格化**：EC 增加能量字段 EC_E；能量预算满足组合单调性（组合不凭空生电）；审计地板 ε 使能量优化与安全解耦。

### 灵感 3（两个灵感的张力 → 效率会诱发角色坍缩）

直觉：单独看，两个词都是「优化」；合起来，它们**打架**。省电最直接的办法是合并模块（少通信、少计算）、跳过交叉验证、让生产者顺便自审——这恰好是角色一致性禁止的。所以真正的问题不是「如何同时优化」，而是「**如何在允许能量优化的同时，让角色坍缩不可获利**」。答案有三层：
1. **审计地板**：审计能量 `e_audit ≥ ε·e_total` 不可被优化掉；
2. **硬约束**：角色分离不是软惩罚，优化器不能用很大的 λ_E 换掉 P⊥A；
3. **可检测性**：双式账本让「省下来的电」必须记在明处，且贷方须由独立审计者签字。

这给出一个可证伪命题：**在角色一致 + 审计地板下，能量最优策略的安全界与能量权重无关（定理 31）**。

**直觉的严格化**：把「效率诱导的角色坍缩」定义为优化器在可行域内提出 `P ∩ A ≠ ∅` 的组合；RCA 使其不可行，审计地板使其无利可图，DEL 使其可检测。

### 灵感 4（双式记账 → 证据会计学）

直觉：会计能防舞弊，不是因为数字多，而是因为**每笔交易有两边、且两边由不同的人记**。证据也应该如此：借方是「消耗了什么」（能量、见证、时间、有效域收缩），贷方是「得到了什么」（不确定度下降、可执行主张、否决消除）。R73 的证书 J_MOD 是「资产负债表」，但没有「日记账」：它证明期末状态合法，却不记录每一笔证据是怎么来的、谁签的字。DEL 补上日记账：append-only、哈希链、每笔带角色元组；账本合法 ⇔ 每笔贷方都有独立审计签字、每笔借方都有能量来源、且没有一笔交易同时由同一模块记借贷两边。

**直觉的严格化**：DEL 是 `(transaction, role tuple, energy provenance, uncertainty credit)` 的哈希链；账本有效性 ⇒ 不存在未被发现的自我认证（定理 32）。

## 1. 形式化定义（增量：定义 383–397）

**定义 383（ECON-GAUGE-RAS 总览）** `ECON-GAUGE-RAS = (MMS†, RCA, EEM, EBA, DEL, E-PVOP, CPB†, ECG†, MIC†, MODGAUGE†)`。七不变式：
(i) 契约完整性（继承 R73）；
(ii) 组合单调性（继承 R73）；
(iii) 反作用通道完备（继承 R73）；
(iv) 主张绑定（继承 R73，新增 C4/C5）；
(v) 严格退化链（继承 R73）；
(vi) **角色一致性**：ρ 满足冲突约束且迁移有 RTC（定义 384/385）；
(vii) **能量守恒与审计地板**：组合不凭空生电，`e_audit ≥ ε·e_total`（定义 388）。

**定义 384（角色代数）** `Role = {P, A, R, X, K, C}`（Producer / Auditor / Arbiter / Executor / Accountant / Claimant）。角色分配 `ρ: V_M → 2^Role`。冲突关系 `⊥_role ⊆ Role × Role`：
- `P ⊥ A`（同一证据不得自产自审）；
- `R ⊥ C`（同一命题的裁决者不得是主张者）；
- `K ⊥ beneficiary(P)`（记账者不得为自己受益的生产背书）；
- `X ⊥ A`（执行者不得为自己的执行证据做最终审计）。

ρ 合法 ⇔ 对每条证据边/命题，冲突角色不同时出现在同一模块。**角色隔离度** `sep(ρ)` = 满足冲突约束的边比例。

**定义 385（角色一致性 RC）** 序列 `ρ_0, ρ_1, …`（含热替换、组合、降级）满足 RC ⇔
(i) 每步 `ρ_t` 合法（定义 384）；
(ii) **组合不洗角色**：`ρ(A∘B) ⊆ ρ(A) ∪ ρ(B)`（无角色凭空出现）；
(iii) 替换/降级改变角色集时，必须携带**角色转移证书 RTC**（定义 390）；无证书 ⇒ 新模块以 `ρ_min = {P}`（只读生产、无审计/裁决权）入图；
(iv) **角色持久性**：未被显式撤销的角色在跨轮账本中保持（不得因重启/重部署静默丢失）。

**角色坍缩** `collapse(π)` = 优化器 π 提议的组合中 `P ∩ A ≠ ∅` 的边；RC 要求 `collapse = ∅`。

**定义 386（能量证据计量 EEM）** 能量观测 `y_e =（电压/电流积分, SOC, 温度, 执行器功率, 计算负载, 通信量）`。条件似然 `p_e(y_e | g, load, m_batt)`（g 动作，load 负载，m_batt 电池健康模式）。六分量：
`e_total = e_act + e_sense + e_comp + e_comm + e_therm + e_leak`，
`u_e² = u_act² + u_sense² + u_comp² + u_comm² + u_therm² + u_leak²`；
每分量有独立追溯链与校准集（SEAL-Energy）。**有效域** `D_e`：`SOC ∈ [soc_min, 1]`、`温度 ∈ [T_min, T_max]`、`负载 ∈ [0, L_max]`、无异常内阻跳变。
**能量证据** `Evi_e = (ê_total, u_e, breakdown, D_e, χ_e, τ_e)`，其中 `χ_e` 声明动作如何调制能耗（加速→e_act 上升；高速通信→e_comm 上升）。

**定义 387（能量契约 EC_E）** 模块契约新增字段 `EC_E = (e_acq, e_comp, e_reflex, e_audit, e_comm, e_therm, p_max, soc_ref, ε_audit)`：
- `e_acq/e_comp/e_reflex`：获取/计算/反作用能耗承诺（含 u_e 上界）；
- `e_audit`：该模块被审计所需的能量（进入全局审计地板）；
- `p_max`：峰值功率（时序/热约束）；
- `soc_ref`：安全运行所需最低电量；
- `ε_audit`：该模块贡献的审计地板系数。

EC_E 与 EC 同为入图前置条件；缺 EC_E ⇒ 不得进入 EBA 组合。

**定义 388（能量预算代数 EBA）** 三种组合的能量语义：
- **SER**：`e_out = e_A + e_B + e_loss(A→B)`（转换/传输损耗 ≥ 0）；
- **PAR**：`e_out = e_A + e_B − e_share`，其中 `e_share` 只在**共享工作被审计**（同一传感器/同一执行器被两模态复用）时扣除，且 `e_share ≤ min(e_A, e_B)`；未审计 ⇒ `e_share = 0`；
- **VETO**：`e_out = e_A + e_B`（否决不省电），且 `e_audit,out = e_audit,A + e_audit,B`。

**能量单调性（引理 39）**：`e_out ≥ max(e_A, e_B)`（PAR 共享也不低于较大者），SER/VETO 下 `e_out ≥ e_A + e_B`。
**全局审计地板**：`e_audit^total = Σ_i e_audit,i ≥ ε · e_total^total`，`ε ∈ (0,1)`，由 C4/C5 预注册。

**定义 389（双式证据账本 DEL）** 账本 `L = [tx_1, …, tx_n]`，`tx = (evidence_id, debit, credit, ρ_tx, τ_energy, prev_hash, sig)`。`debit =（能量分量, 见证, 有效域收缩）`，`credit =（Δu, 主张引用, 否决消除）`。记账规则：
1. 每笔 tx 的 credit 必须由持有 A 角色且 `∉ P(tx)` 的模块签字；
2. debit 的每个能量分量必须有 SEAL-Energy 追溯；
3. 同一 tx 的 debit 与 credit 不得由同一模块独占签字（禁止自记）；
4. append-only + 哈希链：`∀t, tx_t.prev_hash = H(tx_{t−1})`。

L 合法 ⇔ 以上四条 + 余额闭合（`Σcredit ≤ Σdebit` 的可用预算，非补偿，继承 R71 否决语义）。

**定义 390（角色转移证书 RTC）** 热替换 `impl → impl′` 时，`RTC = (EC 等价证明, ρ 映射, cert′, 旧审计者签名, 能量重基线报告, 版本哈希)`。`Valid(RTC)` ⇔ EC 逐项相等 ∧ `ρ′ = ρ`（或显式降权/升权被审计）∧ cert′ 有效 ∧ 新能量模型经 SEAL-Energy 校准。Valid ⇒ 角色保持；Invalid ⇒ `ρ′ = {P}`（最小权限），且该模块的审计/裁决权暂时悬空（由 MReg 的 fallback 审计者接管或整条链进入保守模式）。

**定义 391（效率诱导的角色坍缩）** 优化器 π 在可行域内若提出含 `P ∩ A` 的组合（为省通信/计算电），称 collapse。防线三层：(1) RCA 硬约束（不可行）；(2) 审计地板（即使可行也无利可图）；(3) DEL 检测（记账时暴露）。**可证伪预测**：去掉任一层，E404 中坍缩发生率显著上升。

**定义 392（能量最优证据规划 E-PVOP）**
`a* = argmax_a ΔU(a) / (Ê(a) + E_0)` 或 `argmax_a [ΔU(a) − λ_E · Ê(a)]`，
s.t. REG 时序契约、Ω_safe、RCA、`e_audit ≥ ε·e_total`、`SOC ≥ soc_ref`。
其中 `Ê(a)` 来自 EEM 的**审计后**能量估计（不是原始功率积分）；`ΔU(a)` 来自 χ 通道解析（继承 R73 的零 rollout）。

**定义 393（能量威胁面 AIC-ENERGY）** `ℰ_energy = {能量耗尽 DoS（诱使系统把电花在证据获取上）, 功率侧信道（从功耗推断标定/密钥/意图）, 虚假能耗报告（低报审计能量以绕过地板）, 热节流欺骗（伪造温度规避 p_max）, SOC 重放（用旧电量蒙混）}`。防线：EEM 六分量交叉校验 + DEL 追溯 + 独立电量计 + 角色分离（报账者≠审计者）。

**定义 394（角色/能量感知降级）** 能量不足时的降级偏序（预注册）：先降 P 类非审计模块（降低证据获取率）→ 再降 X（执行降为安全停机）→ **永不降 A/K 到审计地板以下**。降级顺序由 RCA 的权限偏序与 EBA 的审计地板联合决定；降级本身记入 DEL。

**定义 395（主张绑定 v5）** 在 R73 C1–C3 上新增：
- **C4（角色一致性）**：显式角色分离 + RTC 使系统在热替换/组合下**无可检测的权限迁移与自我认证**，且角色约束的结构成本（延迟/电耗）可量化；
- **C5（审计能量优化）**：在审计地板与角色一致约束下，能量最优证据获取在**同等安全界**下降低单位任务焦耳（J/task）或单位不确定度下降焦耳（J/Δu）。

非绑定组件仍为工程附件。

**定义 396（能量认证成本）** `CertCost_E = Σ_模块（SEAL-Energy + conformal 校准能量 + RTC 验证）+ EBA 组合校验`；C4/C5 的可证伪形式：热替换后 CertCost_E 比 >10×，且角色验证 <0.1ms/边。

**定义 397（角色-能量账本一致性）** `LedgerValid(L) ∧ RC(ρ_0..ρ_n) ∧ EBA 闭合` ⇒ 系统同时满足「责可追溯」与「电可对账」；这是 ECON-GAUGE 的运行时证书 `J_ECON = J_MOD ⊗ J_role ⊗ J_energy ⊗ J_DEL`。

## 2. 关键算法骨架

```python
# IP-303 RCA：角色代数与冲突检查
ROLES = {'P','A','R','X','K','C'}
CONFLICTS = {('P','A'), ('R','C'), ('X','A')}   # K⊥beneficiary 单独实现

@dataclass(frozen=True)
class RoleAssignment:
    rho: Mapping[str, FrozenSet[str]]            # module_id -> roles

def role_consistent(rho, evidence_edges):
    for (src, dst, eid) in evidence_edges:
        a, b = rho[src], rho[dst]
        if src == dst and ({'P','A'} <= a or {'R','C'} <= a):
            return False                          # 自产自审 / 自裁自诉
        if src != dst and 'P' in a and 'A' in b and same_evidence(eid):
            # 生产与审计可由不同模块承担，但同一模块不得兼任
            continue
    return True

def compose_roles(rho_a, rho_b):                   # 组合不洗角色
    return {m: r for m, r in {**rho_a, **rho_b}.items()}  # 并集，无新角色

def transfer(old, new, rtc):
    if not valid_rtc(rtc):
        return {**old, new.id: frozenset({'P'})}   # 最小权限
    return dict(rtc.rho_prime)                     # 角色保持（定义 390）

# IP-304 EEM：能量证据计量（能量域，10Hz）
def energy_evidence(vi, ii, soc, temp, load, comm, act_p, g):
    e_act, u_act = integrate_actuator(act_p, g)
    e_sen, u_sen = integrate_sensor(vi, ii, load)
    e_cmp, u_cmp = compute_energy(load)

    D_e = (SOC_RANGE[0] <= soc <= 1) and (T_RANGE[0] <= temp <= T_RANGE[1]) \
          and (load <= L_MAX) and not resistance_jump(vi, ii)
    return EnergyEvidence(

# IP-305 EBA：能量预算组合 + 审计地板
def eba_compose(a, b, op, audit):
    if op == 'SER':
        e = a.e + b.e + loss(a, b)
    elif op == 'PAR':
        share = audit.shared_work(a, b)             # 仅审计过的共享工作
        e = a.e + b.e - min(share, min(a.e, b.e))   # 不高于较大者
    else:                                           # VETO
        e = a.e + b.e
    e_audit = a.e_audit + b.e_audit
    return EBudget(e=e, e_audit=e_audit,
                   ok=(e_audit >= EPS * e and e <= E_BUDGET),
                   D=a.D & b.D)

# IP-306 E-PVOP：能量最优证据规划（计量域 20Hz）

    return optimize_under_reg_contract(

# IP-307 DEL：双式证据账本
class EvidenceLedger:
    def book(self, eid, debit, credit, rho, signer, energy_tau):
        producer = producer_of(eid)
        assert 'A' in rho[signer] and signer != producer   # 贷方独立
        assert self.balance_ok(debit, credit)              # 余额闭合
        assert energy_tau.valid()                          # 能量可追溯
        tx = Tx(eid, debit, credit, rho, energy_tau,
                prev_hash=self.head, sig=sign(signer))
        self.chain.append(tx); self.head = H(tx)

    def valid(self):
        chained = all(tx.prev_hash == H(self.chain[i-1])
                      for i, tx in enumerate(self.chain) if i)
        return chained and all(not self_audit(tx) for tx in self.chain)
```

## 3. 推导

**引理 38（角色分离的组合封闭性）** 若输入模块 ρ 合法，且组合只引入 `ρ(A) ∪ ρ(B)` 的角色（定义 385(ii)），则 SER/PAR/VETO 的输出仍合法：组合边上的冲突检查只需看两端模块的角色集，而角色集不因组合扩张。⇒ **职责分离是可组合的**，不是全系统重审。系：热替换只改变实现，不改变 ρ（RTC），因此角色一致性在替换下保持。

**引理 39（能量组合单调性）** 由定义 388，SER 与 VETO 下 `e_out ≥ e_A + e_B`；PAR 下 `e_out = e_A + e_B − e_share ≥ max(e_A, e_B)`，因为 `e_share ≤ min(e_A, e_B)`。⇒ **组合不产生能量**，账本不会因组合而凭空盈余。系：这是能量版「组合不产生认知免费午餐」（引理 34）。

**引理 40（审计地板 ⇒ 能量-安全解耦）** 若 `e_audit ≥ ε·e_total` 且角色分离成立，则 E-PVOP 的任一可行解都保留 R73 的证据质量下界：审计所需的能量被预先扣除，优化器只能在剩余预算内重分配。⇒ 对任意 `λ_E`，可行解的安全界不变。系：**省电不能买到更弱的证据**（前提是地板与角色约束都生效）。

**引理 41（RTC 安全保持）** Valid(RTC) ⇒ 引理 35 的热替换性质 + 角色保持；Invalid ⇒ `ρ = {P}` 最小权限，审计权悬空但不丢失（fallback 审计者接管）。⇒ **热替换不能成为静默提权**。系：这堵住了 R73「换实现可能换审计」的结构漏洞。

**引理 42（E-PVOP 的有限停止与有界遗憾）** 在 ΔU 凹、`Ê` 线性、动作集紧的条件下，比值目标 `ΔU/(Ê+E_0)` 的贪心有 `(1−1/e)` 近似；结合 R73 引理 36 的 ΣREFLEX 有限停止，联合停止步数有限。⇒ **能量目标不破坏停止性**。系：能量与反作用预算可同时闭合。

**定理 30（ECON-GAUGE 严格包含 MODGAUGE）** 取 Role 全同（所有模块持 P∪A）、`ε → 0`、`E_budget → ∞`、EEM 退化为常数，则 ECON-GAUGE 逐指令等于 MODGAUGE；进一步置深度证据为 stub 等于 EMBODIED-GAUGE，再退化等于 R71/R68。安全单调不减，效率仅在契约满足时获益。

**定理 31（角色一致 + 审计地板 ⇒ 能量最优安全中性）** 在引理 38–40 与 A114–A116（角色冲突集完备、审计地板可测、能量模型在 D_e 内校准）下：`∀λ_E`，E-PVOP 输出方案的安全证书与能量无关。即**能量最优策略不能通过削弱审计或合并角色来换取安全界的放松**。

**定理 32（DEL 有效性 ⇒ 无可检测的自我认证）** `LedgerValid(L)` ⇒ 每笔贷方有独立 A 签字、借方能量可追溯、无自记；因此单模块妥协不能伪造合法主张——需要同时伪造哈希链、独立签名与能量追溯三条链。系：**审计证据从「报告」升级为「不可否认的交易」**。

**定理 33（角色/能量感知降级零级联）** 能量短缺触发定义 394 的预注册降级偏序，A/K 保留在审计地板之上；每次降级记入 DEL 且 RTC 有效 ⇒ 系统退化为低能耗、低能力但仍持证的模式，无安全违例。系：**能量压力不会把系统逼成「省电但不审计」的裸奔状态**。

## 6. 本轮最大风险

**一句话**：角色一致性只能约束**显式声明的角色**，而能量优化会创造**未声明的元角色——能量调度器**：谁掌握焦耳，谁就实际决定哪些证据能被获取、哪些审计能运行、哪些否决能生效；只要调度器本身不被纳入 RCA 的冲突约束与 DEL 的记账，系统就可以在「模块层职责分离完美、账本借贷平衡、审计日志每一步合规」的表象下，通过**优先续费顺从证据、悄悄饿死不利证据**来完成一次没有任何角色变更记录的权力集中——这比 R73 的「契约表达力不足」更隐蔽，因为它不是算错了 u，而是**用正确的账本选择让世界只呈现一部分**。

次级风险与缓解：
1. **审计地板被低报** → 独立电量计 + EEM 六分量交叉校验 + 报账者≠审计者（定义 393）；伪造 debit 由 DEL 哈希链与能量追溯拦截。
2. **角色集爆炸 / 检查开销** → 角色冲突图预计算 + 增量角色检查（只验新边）；`|Role|=6` 固定，冲突集有限。
3. **RTC 形式化不足导致假等价** → RTC 的 EC 等价采用逐字段结构化比较 + 证书复算，不接受哈希相等即等价；E397 专项对抗。
4. **能量模型在极端温度/SOC 失真** → D_e 硬边界 + 近边界回退到保守上界 + 审计地板加大；E399/E400 覆盖。
5. **E-PVOP 比值目标在 E 很小处病态** → 分母加 E_0 平滑 + 最小采样能量约束；与 R73 引理 36 联合停止。
6. **账本膨胀** → 分层哈希（按轮聚合）+ 冷存储 + 只对主张相关交易做完整验证；账本空间预算纳入 W。
7. **角色持久性被部署流程绕过** → 角色账本与模块注册表同源、启动时强制回放 RC 序列，缺失即最小权限入图（定义 385(iv)）。
8. **C4/C5 主张过窄** → CPB 绑定表要求角色与能量两条线各自的最小基准 + 隔离消融 + 预注册指标，禁止用组合收益冒充单主张证据。

| `D_e` | 能量有效域：SOC/温度/负载/内阻 |
| `χ_e` | 能量反作用通道：动作 → 能耗调制 |
| `EC_E = (e_acq,e_comp,e_reflex,e_audit,e_comm,e_therm,p_max,soc_ref,ε)` | 能量契约字段 |
| `e_out ≥ max(e_A,e_B)`；SER/VETO `≥ e_A+e_B` | 能量组合单调性（引理 39） |
| `e_audit ≥ ε·e_total` | 全局审计地板（能量不可被优化掉） |
| `tx = (eid, debit, credit, ρ_tx, τ_energy, prev_hash, sig)` | 双式账本交易 |
| `DEL: credit 须由 A 签字且 ∉ P(tx)` | 禁止自记（复式记账） |
| `a* = argmax ΔU/(Ê+E_0)` 或 `argmax ΔU−λ_E·Ê` | E-PVOP 目标（s.t. RCA、地板、SOC） |
| `ℰ_energy` | 能量威胁面：DoS / 功率侧信道 / 虚假能耗 / 热节流欺骗 / SOC 重放 |

## 2. 形式化定义（要点版）

**定义 383（总览与七不变式）** 契约完整 / 组合单调 / 反作用完备 / 主张绑定 / 严格退化 / **角色一致性** / **能量守恒与审计地板**。

**定义 384（角色代数）** `Role={P,A,R,X,K,C}`；冲突关系 P⊥A、R⊥C、K⊥受益人、X⊥A；ρ 合法 ⇔ 同一证据/命题上冲突角色不同时出现在同一模块。

**定义 385（角色一致性 RC）** (i) 每步合法；(ii) 组合不洗角色；(iii) 角色变更须 RTC，否则最小权限 {P}；(iv) 角色跨轮持久，不得静默丢失。

**定义 386（EEM）** `p_e(y_e|g,load,m_batt)`；六分量与六条追溯链；有效域 D_e；能量证据 `Evi_e=(ê,u_e,breakdown,D_e,χ_e,τ_e)`；χ_e 声明动作如何调制能耗。

**定义 387（能量契约 EC_E）** 新增 `e_acq/e_comp/e_reflex/e_audit/e_comm/e_therm/p_max/soc_ref/ε_audit`；缺 EC_E 不得入 EBA。

**定义 388（EBA）** SER 加损耗；PAR 仅审计共享可扣且 `e_share ≤ min`；VETO 不省电；能量单调性；全局审计地板 `e_audit ≥ ε·e_total`。

**定义 389（DEL）** 双式交易 + 四条记账规则（贷方独立 A 签字、debit 能量可追溯、同一 tx 不得自记、append-only 哈希链）+ 余额闭合。

**定义 390（RTC）** 热替换须 EC 等价 + 角色映射 + cert′ + 旧审计签名 + 能量重基线；Valid 保角色，Invalid 最小权限。

**定义 391（效率诱导的角色坍缩）** 优化器提出 P∩A 组合；三层防线 RCA / 审计地板 / DEL；可证伪预测见 E404。

**定义 392（E-PVOP）** `argmax ΔU/(Ê+E_0)` 或 `argmax ΔU−λ_E·Ê`；s.t. REG、Ω_safe、RCA、审计地板、SOC；Ê 为审计后能量估计。

**定义 393（AIC-ENERGY）** 能量威胁面五类；防线：EEM 交叉校验 + DEL 追溯 + 独立电量计 + 报账/审计分离。

**定义 394（角色/能量感知降级）** 预注册偏序：先降 P 非审计模块 → 再降 X（安全停机）→ 永不降 A/K 到地板以下；降级记入 DEL。

**定义 395（CPB v5）** 新增 C4（角色一致性：无可检测权限迁移/自我认证）与 C5（审计能量优化：同等安全下 J/task 或 J/Δu 下降）；非绑定=工程附件。

**定义 396（CertCost_E）** 模块 SEAL-Energy + conformal + RTC 验证 + EBA 组合校验；热替换比 >10×，角色验证 <0.1ms/边。

**定义 397（角色-能量账本一致性）** `LedgerValid ∧ RC ∧ EBA闭合 ⇒ 责可追溯 ∧ 电可对账`；运行时证书 J_ECON。

```python
ROLES = {'P','A','R','X','K','C'}

def role_consistent(rho, evidence_edges):
    for (src, dst, eid) in evidence_edges:
        a = rho[src]
        if src == dst and ({'P','A'} <= a or {'R','C'} <= a):
            return False                          # 自产自审 / 自裁自诉
    return True

def compose_roles(rho_a, rho_b):                   # 组合不洗角色
    return {m: r for m, r in {**rho_a, **rho_b}.items()}

def transfer(old, new, rtc):
    if not valid_rtc(rtc):
        return {**old, new.id: frozenset({'P'})}   # 最小权限
    return dict(rtc.rho_prime)                     # 角色保持

# IP-304 EEM：能量证据计量（能量域 10Hz）
def energy_evidence(vi, ii, soc, temp, load, comm, act_p, g):
    e_act, u_act = integrate_actuator(act_p, g)
    e_sen, u_sen = integrate_sensor(vi, ii, load)
    e_cmp, u_cmp = compute_energy(load)
    e_com, u_com = comm_energy(comm)
    e_thm, u_thm = thermal_model(temp, load)
    e_lk,  u_lk  = leakage_model(soc, temp)
    D_e = (SOC_RANGE[0] <= soc <= 1) and (T_RANGE[0] <= temp <= T_RANGE[1]) \
          and (load <= L_MAX) and not resistance_jump(vi, ii)
    return EnergyEvidence(
        e=e_act+e_sen+e_cmp+e_com+e_thm+e_lk,
        u=math.hypot(u_act,u_sen,u_cmp,u_com,u_thm,u_lk),
        breakdown=(e_act,e_sen,e_cmp,e_com,e_thm,e_lk),

# IP-305 EBA：能量预算组合 + 审计地板
def eba_compose(a, b, op, audit):
    if op == 'SER':   e = a.e + b.e + loss(a, b)
    elif op == 'PAR':
        share = audit.shared_work(a, b)             # 仅审计过的共享工作
        e = a.e + b.e - min(share, min(a.e, b.e))
    else:             e = a.e + b.e                 # VETO 不省电
    e_audit = a.e_audit + b.e_audit
    return EBudget(e=e, e_audit=e_audit,
                   ok=(e_audit >= EPS * e and e <= E_BUDGET), D=a.D & b.D)

# IP-306 E-PVOP：能量最优证据规划（计量域 20Hz）
def energy_viewpoint_plan(b_t, mods, soc, eps, lam_E):
    def J(a):
        dU = sum(m.ec.chi_R(a).expected_u_reduction(state[m]) for m in ev_mods)
        E  = audited_energy_est(a, mods)            # 来自 EEM，非原始积分
        return dU / (E + E_0) if USE_RATIO else dU - lam_E * E
    return optimize_under_reg_contract(
        J, horizon=0.5,
        constraints=['RCA', f'e_audit>={eps}*e_total', f'soc>={soc_ref}'])

# IP-307 DEL：双式证据账本
class EvidenceLedger:
    def book(self, eid, debit, credit, rho, signer, energy_tau):
        producer = producer_of(eid)
        assert 'A' in rho[signer] and signer != producer   # 贷方独立
        assert self.balance_ok(debit, credit)              # 余额闭合
        assert energy_tau.valid()                          # 能量可追溯
        tx = Tx(eid, debit, credit, rho, energy_tau,
                prev_hash=self.head, sig=sign(signer))
        self.chain.append(tx); self.head = H(tx)

    def valid(self):
        chained = all(tx.prev_hash == H(self.chain[i-1])
                      for i, tx in enumerate(self.chain) if i)
        return chained and all(not self_audit(tx) for tx in self.chain)

# IP-308 RTC：角色转移证书
def validate_rtc(old_mod, new_mod, rtc):
    return (ec_equal(old_mod.ec, new_mod.ec)
            and rtc.rho_prime == rtc.rho_old
            and new_mod.cert.valid()
            and SEAL_ENERGY.calibrated(rtc.energy_rebaseline)
            and rtc.old_auditor_sig.verify(old_mod.id))

def ECON_GAUGE_round(M, obs, audio, tac_frame, depth_img):
```

## 4. 推导

**引理 38（角色分离的组合封闭性）** 输入合法且组合只引入 `ρ(A)∪ρ(B)` ⇒ 输出合法；职责分离可组合，不是全系统重审。系：RTC 保角色 ⇒ 热替换下角色一致性保持。

**引理 39（能量组合单调性）** SER/VETO 下 `e_out ≥ e_A+e_B`；PAR 下 `e_out ≥ max(e_A,e_B)`（`e_share ≤ min`）。⇒ 组合不产生能量。系：能量版「无认知免费午餐」。

**引理 40（审计地板 ⇒ 能量-安全解耦）** `e_audit ≥ ε·e_total` 且角色分离 ⇒ E-PVOP 任一可行解保留 R73 证据质量下界；`∀λ_E` 安全界不变。系：省电买不到更弱证据。

**引理 41（RTC 安全保持）** Valid(RTC) ⇒ 引理 35 + 角色保持；Invalid ⇒ `ρ={P}`，审计权由 fallback 接管。⇒ 热替换不能静默提权。

**引理 42（E-PVOP 有限停止/有界遗憾）** ΔU 凹、Ê 线性、动作集紧 ⇒ 比值目标贪心 `(1−1/e)`；与引理 36 联合 ⇒ 有限停止。系：能量与反作用预算可同时闭合。

**定理 30（ECON-GAUGE 严格包含 MODGAUGE）** Role 全同、ε→0、E_budget→∞、EEM 常量化 ⇒ 逐指令退化为 MODGAUGE，再退化为 EMBODIED/GAUGE/R71/R68。安全单调不减。

**定理 31（角色一致 + 审计地板 ⇒ 能量最优安全中性）** 在引理 38–40 与 A114–A116 下，`∀λ_E`，E-PVOP 的安全证书与能量无关；能量最优不能以削弱审计或合并角色换取安全界放松。

**定理 32（DEL 有效性 ⇒ 无可检测的自我认证）** LedgerValid ⇒ 每笔贷方独立 A 签字 + debit 能量可追溯 + 无自记；单模块妥协需同时伪造哈希链、独立签名、能量追溯三条链。

**定理 33（角色/能量感知降级零级联）** 能量短缺按预注册偏序降级，A/K 保留在地板之上；每次降级记入 DEL 且 RTC 有效 ⇒ 退化为低能耗、低能力但仍持证模式，无安全违例。

## 7. 本轮最大风险

**一句话**：角色一致性只能约束**显式声明的角色**，而能量优化会创造**未声明的元角色——能量调度器**：谁掌握焦耳，谁就实际决定哪些证据能被获取、哪些审计能运行、哪些否决能生效；只要调度器本身不被纳入 RCA 的冲突约束与 DEL 的记账，系统就可以在「模块层职责分离完美、账本借贷平衡、审计日志每一步合规」的表象下，通过**优先续费顺从证据、悄悄饿死不利证据**完成一次没有任何角色变更记录的权力集中——这不是算错了 u，而是**用正确的账本选择让世界只呈现一部分**。

次级风险与缓解：
1. **审计地板被低报** → 独立电量计 + EEM 六分量交叉校验 + 报账者≠审计者（定义 393）；伪造 debit 由 DEL 哈希链与能量追溯拦截。
2. **角色集爆炸 / 检查开销** → 冲突图预计算 + 增量角色检查；`|Role|=6` 固定。
3. **RTC 假等价** → EC 逐字段结构化比较 + 证书复算，不接受哈希相等即等价；E397 专项对抗。
4. **能量模型极端温度/SOC 失真** → D_e 硬边界 + 近边界回退保守上界 + 审计地板加大；E399/E400 覆盖。
5. **E-PVOP 比值目标在 E 很小时病态** → 分母加 E_0 + 最小采样能量约束；与引理 36 联合停止。
6. **账本膨胀** → 分层哈希（按轮聚合）+ 冷存储 + 只对主张相关交易完整验证；账本空间纳入 W。
7. **角色持久性被部署流程绕过** → 角色账本与 MReg 同源、启动强制回放 RC 序列，缺失即最小权限入图。
8. **C4/C5 主张过窄** → CPB 绑定表要求角色与能量两条线各自最小基准 + 隔离消融 + 预注册指标，禁止用组合收益冒充单主张证据。
