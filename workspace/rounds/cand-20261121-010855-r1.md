# 第 1 轮（UniBot 线 · 技能学习 × 竞赛策略）

> **视角声明**：本文件上一版是同一 UniBot 线的“抓取 × 技能学习 × 地形适应”视角。本轮按新灵感整体重写为“技能学习 × 竞赛策略”视角；保留上一版已核实的情报与工程约束，但不沿用其创新点编号。本线启用新编号：定义 D1–D12、引理 L1–L7、实验 E701–E718。
> **数据纪律**：榜单数字来自 `unibot.unitree.com/leaderboard_data.json`，检索日期 2026-11-17。该文件由 `gen_leaderboard.py` 生成、页面注释标注 “randomly-generated”，且被“排行榜即将公开”遮罩覆盖 ⇒ 它是 **teaser / 占位表**，不是官方终稿。下文只把它当作“任务面与字段结构的规格说明书 + 数量级先验”，不把它的具体排名当作真值。

## 0. 情报底座（沿用已核实事实）

1. 赛事：UniBot 世界挑战赛 / UniBot World Challenge，宇树发起；UniBot-V1 为“通才模型”赛道，基于 UnitLab G1 真机，32 项桌面操作任务，按**平均成功率 + 平均步骤分**排名，覆盖 5 类泛化场景（位置 / 干扰物 / 背景 / 未见物品 / 人为干扰）。
2. 数据：官方 HF collection `unitreerobotics/unibot-v1-challenge-dataset` 恰好 32 个 LeRobot v3.0 数据集，一任务一份，单任务 969–1533 episodes，合计约 32k episodes / 169 h；G1 + Dex1 夹爪；4 路 480×640@30fps AV1 相机（头 stereo ×2 + 左右腕）。
3. 接口：选手本地部署 observation→action 服务；策略需暴露 `metadata` / `get_action(obs)` / `reset()`；`control_space` ∈ {joint, ee} 互斥；`action_chunk_size` 自定；`obs_delta_indices` 同时决定传输观测与时序叠帧；评测端用 cv2 做 `image_resize`；token 在 `metadata` 与每步 `meta.token` 两处校验；评测在 N 台真机上随机顺序执行，必须暴露 8765…8765+N−1 连续端口；官方会采集 per-step 延迟及其波动、动作统计规律性并据此评估可信度。
4. 榜单 teaser 的结构性事实：8 个通才模型 × 32 任务；榜首平均成功率 29.7%；step_score 对 success_rate 回归 `step ≈ 1.337·succ + 0.09`，R²=0.9955；8 个模型跨任务相对优劣的 Kendall τ 均值仅 0.064；per-task oracle 33.96，top-2 上界 32.22；最难任务集中在插入 / 旋转 / 细粒度摆放（Plug In Ethernet 17.7、Unlock 20.1、Spell robot 21.8）。
5. 外部对照：RoboDojo 真机榜最强策略平均成功率 12.8%，人类 100%，失败被描述为“能完成大部分步骤，却在最后的对齐 / 插入 / 放置 / 恢复阶段崩”。这说明“最后一环”是当前具身基座的共性断点，不是 UniBot 独有怪癖。

## 1. 直觉：两个灵感的第一性原理

### 1.1 技能学习 —— “通用”不是一个大技能，而是一组可复用、可组合、可失效的小技能

**直觉解释**：如果 32 个任务真的共享同一个“通用操作能力”，那么模型在任务间的相对强弱应该高度一致；但 teaser 榜里 8 个模型的跨任务 Kendall τ 均值只有 0.064，说明“谁更强”在任务间近乎准正交。更合理的解释不是“有 8 种不同的通用智能”，而是：**每个模型掌握了不同的技能子集，而 32 个任务只是这些技能的不同组合方式**。例如“插入以太网线”和“开药瓶”共享“对准—接触—微调—释放”的技能骨架，但对“旋转”“细捏”“抗干扰”的依赖不同。因此，技能学习的正确单位不是“任务”，而是**可跨任务复用的技能单元**；正确目标不是“把 32 个任务都训一遍”，而是**学到一套能被 32 个任务复用的技能库，并知道每个技能在哪些任务上可靠、在哪些边界上会失效**。

**严谨定义（先给骨架，D1–D6 在产物区展开）**：把技能建模为带前提条件、终止条件和效果模型的闭环控制器（option）：`s = (I_s, π_s, β_s, E_s)`。任务 `t` 被表示成技能图上的一条路径 `(s_1, …, s_L)`，任务成功率近似为路径上各技能在任务上下文中的能力乘积 `P_t ≈ ∏ C_{s,t}`。这一步把“通用能力”从一个不可解释的标量，变成一张**技能—任务能力矩阵** `C`。有了 `C`，我们才能回答两个竞赛中最关键的问题：**哪个技能最值得练？它在哪些任务上是负迁移？**

### 1.2 竞赛策略 —— 榜单不是测量仪，而是一场有限样本的排名赛

**直觉解释**：很多人把榜单当成“真实能力的无偏测量”，于是全力提高平均成功率。但竞赛的计分是**有限样本的样本均值**：每个任务只跑有限个 episode，随机顺序、N 台真机、5 类泛化场景，还要经过网络与部署链路。于是“我们的真实均值更高”与“我们最终排名更高”不是同一件事。如果两个方案的均值只差 1–2 分，而评测噪声的标准差有 3–5 分，那么谁排前面很大程度上是抽签。竞赛策略的第一性原理因此是：**优化“进入前 k 名的概率”，而不是优化“平均分的点估计”**；在均值接近时，**降低方差、避免尾部灾难、把资源投向“排名边际价值”最高的任务**，比继续卷平均分更划算。

**严谨定义（先给骨架，D7–D12 在产物区展开）**：设任务 `t` 的真实成功率 `p_t`，评测 `n_t` 个 episode，观测 `p̂_t ~ Binomial(n_t, p_t)/n_t`；总分 `S = (1/T)Σ_t (α p̂_t + β q̂_t)`。我们最大化的是 `P(rank(S) ≤ k)`，而不是 `E[S]`。在这个目标下，可以定义每个任务的**排名边际价值**（该任务的结果改变我们排名的概率）与每个技能变体的**单位成本排名增益**，从而把“练什么技能”与“把算力花在哪”统一成一个预算分配问题。

### 1.3 合成：SCOPE —— 技能组合是资产，竞赛策略是资产配置

**直觉解释**：技能学习回答“我们有什么可复用的能力”，竞赛策略回答“在有限算力、有限评测样本、有限提交次数下，先练哪个、怎么组合、怎样避免翻车”。两者相乘，得到一个比“再训一个更大的 VLA”更符合赛制的系统：

**SCOPE = Skill Competence-Optimized Policy Engine（技能能力优化的策略引擎）**：
1. **技能层**：从 32 个任务数据中学习可复用的技能单元，构建技能图与技能—任务能力矩阵；
2. **度量层**：用配对评测、分层 bootstrap 和 OOD 检测，估计“技能在哪个任务/场景上可靠”；
3. **竞赛层**：用排名概率目标做预算分配，决定练哪个技能、保留哪个变体、把验证样本花在哪；
4. **提交层**：用冠军— challenger、健康检查、端口隔离、延迟兜底和基线回退，控制尾部风险；
5. **工程层**：单 checkpoint、单 API、N 端口并发、chunk 缝合与可审计。

一句话：**不是训练一个“更通用的模型”，而是训练一个“知道自己的技能在哪里可靠、并能在竞赛中把可靠技能配置到正确任务上的系统”。**

## 2. 量化观察：为什么“技能组合 + 排名概率”比“再训一个更大的 VLA”更划算

| 观察 | 数值（teaser，仅作数量级） | 推出的设计 |
|---|---|---|
| step_score 与 success_rate 近共线 | `step ≈ 1.337·succ + 0.09`，R²=0.9955 | 优化终态成功即可；不要为“多推进几步”牺牲成功率 |
| 模型跨任务强弱近正交 | Kendall τ 均值 0.064，28 对里仅 1 对 \|τ\|>0.2 | “通用”是技能向量；单 checkpoint 内的技能条件化有真实空间 |
| per-task oracle 上界 | 33.96 vs 最好单模型 29.70 ⇒ +4.26 | 技能路由/组合的上界存在，但必须先证明可兑现 |
| top-2 混合上界 | 32.22 ⇒ +2.52 | 即便只做“两技能选一”，也有可观空间 |
| 最难任务集中在插入/旋转/细粒度摆放 | Plug In Ethernet 17.7、Unlock 20.1、Spell robot 21.8 | 技能瓶颈在“对准—接触—微调—释放”链，而非“看见物体” |
| 时长与成功无关 | 任务内 corr(dur, succ) 均值 −0.011 | “做得快”没有红利；不要为提速牺牲可靠性 |

**本轮新增的三个竞赛策略计算（用于决定资源分配，而非预测真实排名）**：

1. **有限样本的排名噪声**。若每任务评测 `n` 个 episode，真实成功率约 0.3，则单任务成功率的标准误约 `sqrt(0.3×0.7/n)`。取 `n=20`，单任务标准误约 10.2 个百分点；32 个任务平均后的标准误约 1.8 个百分点。若再把步骤分按 `1.337` 的系数并入，总分的标准误约 4.2 分；`n=50` 时约 2.7 分，`n=100` 时约 1.9 分。**含义**：在没有配对设计的情况下，榜首与第 3–5 名之间 1–3 分的差距可能完全在噪声内；因此“冲榜”不能只看点估计，必须看置信区间与排名概率。

2. **尾部灾难的期望损失**。总分是 32 个任务的等权平均。若 N 台真机中有一台端口在评测期间故障，且故障覆盖该端口负责的全部 episode，则大约 `1/N` 的任务被记为零分；按均分 30 分算，期望损失约 `30/N` 分。N=3 时是 **10 分**，已经超过 oracle 技能路由的 +4.26 分。**含义**：一个端口故障或一次握手失败，足以吞掉所有算法创新；**可靠性工程的优先级不低于模型创新**。

3. **排名概率对均值和方差的敏感度**。假设我们的总分近似 `N(μ, σ²)`，追赶分数线为 `c`。若 `μ−c=2`、`σ=4`，进入前 k 的概率约 0.69；若把 `σ` 降到 2，概率升到 0.84——**降低 2 分方差与提高 2 分均值同样值钱**。而技能边界检测、冠军—challenger、基线回退、延迟兜底，正是降方差的手段。**含义**：竞赛策略不应只问“哪个技能能涨点”，还要问“哪个改动能减少翻车”。

**技能分解的直观例子**：若一个插入任务的技能链有 6 个环节，每个环节能力 0.8，则任务成功率约 `0.8^6 ≈ 0.26`；把最弱的 0.6 提到 0.8，成功率可接近翻倍。这解释了为什么“最后一环”类任务整体最差，也说明**按技能瓶颈分配训练预算**比按任务平均分配更有效**。**

## 3. 研究问题（本轮版）

- **Q1（技能粒度）**：什么粒度的技能单元既能跨至少 2 个任务复用，又能从官方数据中稳定分割、在测试时被可靠触发？是“抓/放/推/插/转”这种运动原语，还是“对准—接触—微调—释放”这种闭环阶段？
- **Q2（单 checkpoint 内的技能学习）**：在“单模型通才”赛制下，技能库应如何组织？共享主干 + 技能条件化适配器 + 技能门控是否合规？最严格的“单技能降级形态”还剩多少收益？
- **Q3（技能能力的可测性）**：能否用官方 32 个数据集估计技能—任务能力矩阵 `C`，并用它预测“哪个技能在哪个任务上是负迁移”？能力矩阵的秩、稳定性与跨场景漂移有多大？
- **Q4（技能边界）**：当测试时出现未见物品/背景/干扰物，如何判断当前技能的前提条件已被违反，从而在“继续执行—换技能—退回基线”之间做保守选择？误判的代价如何量化？
- **Q5（竞赛预算）**：给定有限算力与有限真机时段，如何把预算分配到“最可能改变排名”的技能与任务上？排名概率目标与平均分目标在什么条件下产生不同的最优决策？
- **Q6（尾部风险）**：如何用冠军—challenger、端口隔离、延迟兜底和基线回退，把“单次故障导致整场评测崩盘”的概率压到可接受范围？如何用可审计指标自证可信度？

## 4. 设计原则

- **P1 排名概率优先于平均分点估计**：所有改动都要能回答“它是否提高进入前 k 名的概率”，而不只是“它是否让离线均值涨了 1 分”。
- **P2 技能必须可复用、可组合、可失效**：一个技能至少服务 2 个任务才允许进入技能库；每个技能必须带前提条件、终止条件和失效检测，禁止退化成 32 个任务专用策略。
- **P3 单 checkpoint、单 API、单模型叙事**：技能库是同一 checkpoint 内的条件化模块；必须准备“单技能/单专家降级形态”并实测代价，合规优先于最优。
- **P4 先测量后投入**：任何技能变体先过配对评测与统计显著性闸门，再进入主线；禁止用 teaser 占位榜调参。
- **P5 尾部风险预算化**：给端口故障、延迟超时、动作异常、OOD 误判分别设预算；任何一项超预算，自动退回安全基线。
- **P6 失败驱动，而非成功模仿**：技能学习的主要数据来源应包含失败与恢复片段；只学“成功轨迹”会把“最后一步崩”的分布也学进去。
- **P7 公共品优先**：技能切分口径、能力矩阵、评估协议、故障注入脚本应可复用、可审计，便于后续轮次和团队协作。

## 5. 最小可提交闭环（MVP）与退化链

**MVP = 技能切分 + 能力矩阵（SK-01/02） + 排名概率评估器（SK-04） + 安全提交层（SK-05） + 官方基线 VLA**。
理由：没有技能切分与能力矩阵，就不知道“练什么”；没有排名概率评估器，就会把噪声当信号；没有安全提交层，一次端口故障就能抹掉所有收益。技能锦标赛（SK-03）与 OOD 检测（SK-06）作为第二轮增强，不阻塞首个可提交版本。

**退化链（任一环节不可用 ⇒ 行为回退，不漂移）**：
- Level-0 技能路由不可用（任务/阶段识别置信度低）⇒ 退回单技能通用策略；
- Level-1 能力矩阵不可用（样本不足）⇒ 退回均匀技能先验，不做负迁移规避；
- Level-2 OOD 检测不可用 ⇒ 退回保守阈值 + 不换技能；
- Level-3 锦标赛未完成 ⇒ 使用上一版冠军技能；
- Level-4 新链路整体异常 ⇒ 退回**纯基线策略**（永远保留一份能跑通、可信度合规的最小提交）。

## 6. 预期贡献（可验收）

1. **技能—任务能力矩阵**：给出从 32 个官方数据集中自动切分技能、估计 `C_{s,t}` 的方法，并用留出任务/留出场景验证其预测力；这是把“通用能力”从叙事变成可测量对象的第一步。
2. **排名概率优化器**：把竞赛策略形式化为“在有限评测样本与有限算力下最大化进入前 k 名的概率”，给出可复现的 bootstrap/贝叶斯模拟与预算分配算法。
3. **技能锦标赛协议**：用配对评测 + 逐步减半 + 冠军—challenger，把“内部选型”变成可审计的统计决策流程，避免在噪声上过拟合。
4. **技能边界检测**：给出未见场景下的前提条件违反检测与保守回退策略，量化“继续执行 / 换技能 / 退回基线”的代价。
5. **尾部风险工程**：端口隔离、健康检查、延迟兜底、动作限幅与故障注入报告，把“可信度”变成可导出的工程产物。
6. **可复用的评估竞技场**：用官方 32 个数据集做 OOD 切分与配对评估，给出最小可检测效应与样本量建议，让后续每轮迭代不依赖真机时段也能做出统计上站得住的决策。

## 7. 本轮最大风险

**一句话**：本轮把赌注押在“技能分解 + 排名概率优化”上，而最大风险是**我们用来分配资源的“竞赛模型”本身建立在一个占位榜单与有限样本的噪声之上**——一旦把统计上不可分辨的 1–3 分差距当成真实机会，就会把算力投向“排名幻觉”，反而忽略技能在未见场景下的负迁移与单端口故障这类真正会吞掉总分的尾部风险。

## 8. 下一轮迭代计划（深化与修剪）

- **深化**：把技能切分从“阶段标签”升级为“前提条件—效果”可验证的技能图；把能力矩阵从点估计升级为带置信区间的分层贝叶斯模型；把排名概率优化器接入真实评测回放。
- **修剪预案**：若技能—任务能力矩阵对留出任务的预测相关性 `|r| < 0.3`，则砍掉“按能力矩阵做技能路由”的主线，只保留“技能切分 + 失败驱动修复”；若排名概率优化器在回放中不能稳定优于均匀分配，则退回“按任务难度与方差手工分层”的保守策略。
- **保留项**：SK-05（安全提交层）与 SK-08（评估竞技场）在任何情况下不砍，它们决定其他结论是否可信。

# 第 1 轮产物 · 创新点清单 v1（UniBot 线）：**UniBot-SCOPE**

> **SCOPE = Skill Competence-Optimized Policy Engine**（技能能力优化的策略引擎）。
> 本清单是“技能学习 × 竞赛策略”视角的持续迭代载体，第 1 轮为奠基版。上一版以抓握确认 / MoE 路由为中心的编号（IP-01…IP-08、U1–U12、E601–E618）不再沿用；本线启用新的 **SK-01…SK-08、D1–D12、L1–L7、E701–E718**。
> **数据来源纪律**：榜单数字来自 `unibot.unitree.com/leaderboard_data.json`（teaser / 占位表，`generated_from: gen_leaderboard.py`，页面注释标注 “randomly-generated”，官方尚未正式发布），检索日期 **2026-11-17**。凡引用均标注 teaser；一切调参以本地 OOD 切分与真机配对 A/B 为准。

## 0. 本轮结论摘要

**一句话路线**：把“技能学习”编译成**技能库 + 技能—任务能力矩阵**，把“竞赛策略”编译成**排名概率目标 + 预算分配 + 尾部风险控制**，再包一层**单 checkpoint / 单 API / N 端口**的工程壳：

**技能层**（可复用技能单元 / 技能图）→ **度量层**（能力矩阵 / OOD 边界）→ **竞赛层**（排名概率 / 锦标赛 / 预算分配）→ **提交层**（冠军—challenger / 基线回退 / 延迟兜底）→ **工程层**（chunk 缝合 / 端口隔离 / 可审计）。

**为什么是这个组合（三条量化依据）**：

| 证据（teaser，仅作数量级） | 数值 | 推出的设计 |
|---|---|---|
| step_score 与 success_rate 近共线 | `step ≈ 1.337·succ + 0.09`，R²=0.9955 | 只优化终态成功；步骤分没有独立杠杆 → 引理 L1 |
| 8 个模型跨任务强弱近正交 | Kendall τ 均值 0.064 | “通用”是技能向量 → 技能库 + 能力矩阵（SK-01/02） |
| per-task oracle 上界 | 33.96 vs 最好单模型 29.70（+4.26） | 技能组合有空间，但必须用锦标赛证明可兑现（SK-03） |
| 有限样本评测噪声（敏感性分析） | n=20 时总分标准误约 4.2 分；n=50 时约 2.7 分 | 优化排名概率而非均值点估计（SK-04） |
| 单端口故障的期望损失 | N=3 时约 10 分，超过 oracle 上界 | 安全提交层优先于算法创新（SK-05） |

**合规红线（P3）**：单一 checkpoint、单一 API 服务；技能库是同一 checkpoint 内的条件化模块；不用评测侧私有信息；不硬编码任务分支；必须准备“单技能降级形态”并实测其代价。

## 2. 创新点详述

### SK-01 · SkillGraph 技能图谱与可复用技能库（P0）

- **直觉**：32 个任务不是 32 种独立能力，而是若干技能的不同排列。先学“技能字母表”，再用“任务语法”组合，比从零为每个任务训一个策略更省数据，也更可能在未见任务上泛化。
- **与现有方案的差异**：主流做法是“一个更大的 VLA + 更多任务数据”，把技能异质性交给模型容量；我们把技能显式化：**技能 = 带前提/终止/效果的闭环控制器**，技能库是共享主干 + 技能条件化适配器，任务是指向技能图的路径。
- **技术可行性**：中–高。官方数据有 4 路相机、arm/gripper/EE 状态与动作，可按“夹爪开合变化 + 接触/位移事件 + VLM 语义标签”做技能切分；技能标签用规则 + VLM 批量伪标 + 人工抽检 5%。技能条件化可用 skill token + 轻量适配器，保持单 checkpoint。
- **所需资源**：数据 = 官方 32 数据集（≈32k eps / 169 h）；算力 = 8×A100 / 2–3 天（2–7B 主干 + 轻量技能适配器）；接口 = 无新增字段。
- **落地步骤**：
  1. 统一 LeRobot v3.0 解码，对齐 4 相机、arm/gripper/EE 与 action 键名；
  2. 定义初版技能词汇表（reach / grasp / lift / transport / align / insert / rotate / place / release / push / sweep / hook / retreat）；
  3. 用夹爪状态、EE 速度、物体相对位移与 VLM 标签做多信号切分；
  4. 训练“共享主干 + 技能 token”基线，先验证“技能条件化本身是否涨点”；
  5. 构建技能图：节点是技能，边是“技能后接”的兼容性/转移概率；任务路径由数据统计得到；
  6. 做“技能复用覆盖率”审计：每个技能至少服务 2 个任务，否则合并或删除。
- **风险**：①技能切分噪声 ⇒ 双标注器一致性检查 + 人工抽检；②技能词汇表过细 ⇒ 退化为 32 个任务专用策略，违反 P2 ⇒ 用复用覆盖率强制约束；③技能条件化在单 checkpoint 内被判“多模型” ⇒ 先书面确认，并准备单技能降级形态。

### SK-02 · SkillCompetence 技能—任务能力矩阵与路由（P0）

- **直觉**：知道“我们有哪些技能”还不够，必须知道“每个技能在哪个任务、哪个场景上可靠”。能力矩阵是把技能库变成可决策资产的关键：它告诉我们最该练哪个技能，以及某个技能在哪些任务上可能负迁移。
- **与现有方案的差异**：现有方案通常只看任务级成功率，无法归因到技能；我们估计 `C_{s,t}`，并用 `P_t ≈ ∏ C_{s,t}` 的对数线性分解把任务失败拆到技能瓶颈上。这不是又一个“阶段分类器”，而是**用于资源分配的可加性账本**。
- **技术可行性**：高–中。技能在数据中可观测（夹爪/接触/位移），能力矩阵可用“技能起点后的子轨迹成功率”估计；测试时用技能 token + 轻量分类器路由。难点是“技能之间的交互项”会破坏纯乘积假设，需要用混合效应模型或对数线性回归估计交互。
- **所需资源**：数据 = 官方数据 + 技能切分标签；算力 = 中等（能力矩阵估计 + 路由训练）；接口 = 无。
- **落地步骤**：
  1. 对每个技能定义“成功”的可观测判据（抓住、抬起、对齐误差、插入深度、释放后稳定）；
  2. 在留出 episode 上估计 `C_{s,t}` 与置信区间；
  3. 拟合 `log P_t = Σ_s a_{s,t} log C_{s,t} + interaction`，检验乘积假设；
  4. 用能力矩阵做两件事：**训练预算分配**（最弱且最可改的技能优先）与**测试时路由**（低能力技能触发换技能/回退）；
  5. 做负迁移审计：在留出任务/场景上比较“路由策略”与“单技能通用策略”。
- **风险**：①乘积假设不成立 ⇒ 保留交互项，并在报告中同时给出加性与乘积解释；②能力矩阵在未见场景漂移 ⇒ 用 SK-06 的 OOD 检测做门控；③路由错配 ⇒ 低置信时退回单技能。

### SK-03 · SkillTournament 内部技能锦标赛（P0）

- **直觉**：竞赛策略不只用于对外排名，也用于对内选型。与其一次性训练一个巨大模型，不如让多个技能变体在**同一批配对 episode** 上“打比赛”，用逐步减半把算力集中到有希望的变体上。这既省算力，又避免“在噪声上选冠军”。
- **与现有方案的差异**：常见做法是“训几个模型，看验证集均值，挑最高的”；这在小样本下极易过拟合噪声。我们采用**配对评测 + 逐步减半 + 冠军—challenger + 显著性闸门**：只有 challenger 在配对比较中显著优于 champion 才晋升。
- **技术可行性**：高。技能变体可以是不同数据配比、不同技能 token、不同动作头、不同 chunk 策略；评测用官方数据回放 + 少量真机锚点。
- **所需资源**：数据 = 官方数据；算力 = 比全网格搜索省 40%+；接口 = 无。
- **落地步骤**：
  1. 定义冠军（当前安全基线）与 challenger（新技能变体）；
  2. 用配对 episode（同任务、同初始状态、同随机种子）做比较；
  3. 逐步减半：第一轮宽筛，保留前 50%；第二轮配对细评，保留前 2；第三轮显著性检验；
  4. 晋升规则：`LCB(Δ) > 0` 且效应量 ≥ 预注册阈值，才替换冠军；
  5. 记录每次晋升/拒绝的理由，形成可审计的选型日志。
- **风险**：①配对不成立（真机初始状态不可控）⇒ 用同任务分层随机化 + 混合效应模型；②锦标赛过拟合验证集 ⇒ 留出任务/场景双层切分；③challenger 在 OOD 上更差 ⇒ 晋升前必须过 SK-06 的边界测试。

### SK-04 · RankPilot 排名概率优化与预算分配（P0）

- **直觉**：如果评测有噪声，那么“提高平均分”与“提高排名”不是一回事。RankPilot 把竞赛建模成一场带噪声的排名赛：用我们的评测数据模拟“如果现在提交，排名分布是什么”，再算每个任务/技能的**排名边际价值**，把资源投向最可能改变排名的地方。
- **与现有方案的差异**：现有队伍通常按“任务难度”或“平均分提升”手工分配精力；我们按 `P(rank ≤ k)` 的边际增益分配，并且显式建模评测方差、对手强度与尾部风险。
- **技术可行性**：中–高。需要我们的代理评测 + 一个“对手场”模型；teaser 榜只能作为结构性先验（占位表，不能当真），对手模型应用留出模型/历史提交/合理先验构造，并做敏感性分析。
- **所需资源**：数据 = 代理评测结果 + 真机 A/B；算力 = 小（bootstrap/贝叶斯模拟）；接口 = 无。
- **落地步骤**：
  1. 用分层 bootstrap 从我们的评测数据估计每个任务的 `p_t` 后验；
  2. 构造对手场：用 teaser 结构 + 合理先验 + 敏感性网格（不把 teaser 排名当真）；
  3. 蒙特卡洛模拟总分与排名，得到 `P(rank ≤ k)`；
  4. 计算每个任务的 pivotal probability（该任务结果改变排名的概率）与每个技能变体的单位成本排名增益；
  5. 用贪心/本地搜索分配训练与验证预算；
  6. 在真机回放上验证“RankPilot 分配”是否优于“均匀分配 / 难度分配”。
- **风险**：①对手场模型错误 ⇒ 做敏感性分析，只在多个先验下都稳健的决策才执行；②过度优化排名导致平均能力下降 ⇒ 设“平均分不降”约束；③teaser 过拟合 ⇒ 明确禁止用 teaser 具体排名调参。

### SK-05 · SafeSubmit 尾部风险受控提交层（P0）

- **直觉**：竞赛总分是 32 个任务的等权平均，一次端口故障、一次延迟超时、一次动作异常，就可能把若干任务记为零分。按 N=3 台真机估算，单端口故障的期望损失约 10 分，超过技能路由的全部 oracle 上界。**因此，可靠性不是工程附属品，而是竞赛策略的一部分。**
- **与现有方案的差异**：多数提交只保证“能跑”；我们把尾部风险做成**可预算、可注入、可回退**的工程层：健康检查、端口隔离、延迟兜底、动作限幅、异常检测、基线回退、故障注入报告。
- **技术可行性**：高（工程活）。
- **所需资源**：接口 = 官方 client；算力 = 极小；数据 = 无。
- **落地步骤**：
  1. 启动自检：端口 8765…8765+N−1、token 两处校验、metadata 完整性、依赖版本；
  2. 每端口独立 session，`reset()` 清空所有历史状态，禁止跨端口共享可变状态；
  3. 延迟预算：p99 超过阈值时返回上一安全动作的短延拓，并标记 degraded；
  4. 动作限幅与离群检测：只对残差限幅，不改均值，避免压低成功率；
  5. 健康检查失败 ⇒ 自动切到基线策略（champion）；
  6. 故障注入：随机杀端口、加延迟、丢包、错 token、重复 reset，验证恢复率与期望损失；
  7. 导出审计报告：延迟直方图、jerk 分布、chunk 边界失配计数、降级次数、故障恢复记录。
- **风险**：①过度平滑/限幅降低成功率 ⇒ 限幅阈值由数据分布定，只作用残差；②回退策略本身不可用 ⇒ 基线必须定期回归测试；③“动作过于规律”被误判为脚本化 ⇒ 保留策略固有随机性，不做人工“拟人化”噪声。

### SK-06 · BoundaryGuard 技能边界 / OOD 检测（P1）

- **直觉**：技能库最大的敌人不是“不会”，而是“在错误的地方自信地使用”。当测试时出现未见物品、背景、干扰物或人为干扰，技能的前提条件可能已被违反；此时继续执行会把可恢复的失败变成硬失败。BoundaryGuard 的任务是：**在技能失效前察觉，并保守地选择继续 / 换技能 / 退回基线。**
- **与现有方案的差异**：常见做法是“域随机化 + 更大模型”，希望模型自己泛化；我们把“技能前提条件是否满足”显式建模，用 conformal prediction / 密度估计给出带校准的 OOD 分数，并设置保守回退。
- **技术可行性**：中。可用冻结视觉主干 + 技能条件密度模型；阈值的覆盖率用 conformal 校准；难点是“OOD 但任务仍可做”的假阳性。
- **所需资源**：数据 = 官方数据 + 自建 5 轴 OOD 变体；算力 = 小；接口 = 无。
- **落地步骤**：
  1. 为每个技能定义前提条件特征（物体类别/尺寸/位姿、遮挡、背景、干扰物密度）；
  2. 在技能训练分布上拟合密度/能量模型；
  3. 用 conformal prediction 校准“技能适用”阈值，给出覆盖率保证；
  4. 测试时：OOD 分数低 ⇒ 继续；中 ⇒ 换兼容技能；高 ⇒ 退回基线；
  5. 在 5 类泛化场景上做受控实验，量化假阳性/假阴性与成功率。
- **风险**：①OOD 检测把“难但可做”误判为“不可做” ⇒ 保守阈值 + 只在置信度高时回退；②未见物品分布漂移 ⇒ 每轮用新数据重校准；③回退本身引入抖动 ⇒ 回退只在技能边界发生，且受最小驻留时间约束。

### SK-07 · FailureMiner 失败驱动的技能修复（P1）

- **直觉**：官方数据里最有价值的部分可能不是成功轨迹，而是失败与恢复片段。失败片段直接告诉我们“哪个技能在什么条件下崩”，比盲目扩大数据更高效。
- **与现有方案的差异**：常见做法是“只学成功轨迹”或“全量混训”；我们把失败片段按技能归因，生成定向修复数据，只更新对应技能适配器，并做“修复不伤其他技能”的回归测试。
- **技术可行性**：中–高。官方数据以成功演示为主，但可人为构造失败（遮挡、偏移、干扰）或用真机失败日志；技能归因依赖 SK-02 的能力矩阵。
- **所需资源**：数据 = 官方数据 + 合成失败 + 真机失败日志；算力 = 小–中；接口 = 无。
- **落地步骤**：
  1. 收集失败片段并按技能链定位首个失败技能；
  2. 对失败技能做数据增强（初始位姿扰动、遮挡、干扰物、夹爪偏差）；
  3. 只训练该技能的适配器，冻结主干与其他技能；
  4. 回归测试：目标技能提升，其他技能不显著下降；
  5. 记录修复前后能力矩阵变化。
- **风险**：①合成失败不真实 ⇒ 以真机失败日志校准；②定向修复导致灾难性遗忘 ⇒ 冻结主干 + 小适配器 + 回归测试；③失败归因错误 ⇒ 双标注器 + 人工抽检。

### SK-08 · EvalArena 统计功效与评估竞技场（P1）

- **直觉**：如果评估本身没有统计功效，那么所有“涨点”都可能是噪声。EvalArena 的目标不是再建一个仿真器，而是建立一套**能在有限样本下做出可靠决策**的评估协议。
- **与现有方案的差异**：常见评估是“跑一批 episode，看均值”；我们做配对设计、功效分析、分层 bootstrap、代理—真机标定与预注册，明确“多大的差异才值得相信”。
- **技术可行性**：高。官方 32 个数据集可做留出任务/场景切分；真机时段用于锚点标定。
- **所需资源**：数据 = 官方数据；算力 = 小–中；接口 = 无。
- **落地步骤**：
  1. 定义留出切分：留出物体实例 / 背景 / 位置 / 干扰物 / 人为遮挡；
  2. 配对评估：同任务、同初始状态、同随机种子比较策略；
  3. 功效分析：给定方差与样本量，计算最小可检测效应；
  4. 分层 bootstrap 给出置信区间；
  5. 真机锚点：每轮 2–3 个时段，估计代理指标与真机成功率的 Spearman 相关；
  6. 预注册决策规则，禁止事后挑指标。
- **风险**：①代理与真机相关性不足 ⇒ 预注册“|r|<0.3 则砍掉依赖代理指标的微调”；②留出切分泄漏 ⇒ 按任务/场景双层隔离；③样本量不足 ⇒ 先算功效再开跑。

## 3. 符号与定义（D1–D12）

| 符号 | 含义 |
|---|---|
| `s` | 技能单元（option） |
| `G=(S,E)` | 技能图：节点是技能，边是兼容/转移关系 |
| `path(t)` | 任务 `t` 的技能链 |
| `C_{s,t}` | 技能 `s` 在任务 `t` 上下文中的能力（成功率） |
| `C` | 技能—任务能力矩阵 |
| `π` | 单 checkpoint 策略：观测 + 语言 + 技能 token → 动作块 |
| `z_s` | 技能 token（路由结果） |
| `o_t` | 观测（4 相机 + 本体状态 + 语言） |
| `n_t` | 任务 `t` 的评测 episode 数 |
| `p_t` | 任务 `t` 的真实成功率 |
| `S` | 总分（成功率与步骤分的加权平均） |
| `R` | 排名（1 最好） |
| `k` | 目标名次（如进入前 3） |
| `w_t` | 任务 `t` 的 pivotal weight（排名边际价值） |
| `B` | 训练/验证预算 |
| `F` | 安全回退策略（基线） |

**定义 D1（技能单元 / option）** 技能 `s` 是一个四元组 `s = (I_s, π_s, β_s, E_s)`，其中 `I_s` 是前提条件集合（可启动该技能的观测/状态区域），`π_s(a | o)` 是技能策略，`β_s(o)` 是终止条件，`E_s(o, a)` 是效果模型（执行后预期的状态变化）。直觉：技能不是一段固定动作，而是“在什么条件下、做什么、做到什么时候、做完会怎样”的闭环单元。

**定义 D2（技能图与任务链）** 技能图 `G=(S,E)`，边 `(s, s') ∈ E` 表示 `s` 的终止状态可满足 `s'` 的前提条件。任务 `t` 的技能链为 `path(t) = (s_{t,1}, …, s_{t,L_t})`，由官方数据的技能切分统计得到。直觉：任务不是黑盒，而是技能图上的一条路径。

**定义 D3（能力分解）** 任务成功率近似为 `P_t ≈ ∏_{l=1}^{L_t} C_{s_{t,l}, t}^{γ_l} · exp(ε_t)`，其中 `γ_l` 是技能权重，`ε_t` 是交互/残差项。取对数得 `log P_t ≈ Σ_l γ_l log C_{s_{t,l}, t} + ε_t`。直觉：把“任务失败”拆成“哪个技能最弱”的可加账本。

**定义 D4（能力矩阵）** `C_{s,t} = P(技能 s 在任务 t 中成功 | s 被正确触发)`，用留出 episode 估计，并给出置信区间 `[C^-_{s,t}, C^+_{s,t}]`。直觉：能力矩阵是技能库的“资产负债表”。

**定义 D5（技能路由）** `z_s = argmax_s P(s | o, ℓ, phase)`，其中 `ℓ` 是语言指令，`phase` 是当前阶段特征。路由输出技能 token 给单 checkpoint 策略；低置信时退回通用技能 `s_gen`。直觉：技能库不是并列的多个模型，而是一个模型内的条件化选择。

**定义 D6（技能边界 / OOD 分数）** 对技能 `s`，定义 `b_s(o) ∈ [0,1]` 为该观测满足 `I_s` 的校准置信度；用 conformal prediction 在技能训练分布上校准阈值 `τ_s`，使得 `P(b_s(o) ≥ τ_s | o ∈ I_s) ≥ 1−α`。直觉：技能边界不是“感觉不对”，而是有覆盖率保证的统计判据。

**定义 D7（评测噪声模型）** 任务 `t` 的真实成功率 `p_t`，评测 `n_t` 个 episode，观测 `p̂_t = X_t/n_t`，`X_t ~ Binomial(n_t, p_t)`。总分 `S = (1/T)Σ_t (α p̂_t + β q̂_t)`，其中 `q̂_t` 是步骤分。直觉：榜单是带噪声的样本均值，不是真值。

**定义 D8（排名概率目标）** 给定对手场分布 `Ω` 与我们的策略 `π`，目标为 `max_π P_{Ω, noise}(R(π) ≤ k)`，而不是 `max_π E[S(π)]`。直觉：竞赛奖励的是名次，不是平均分的点估计。

**定义 D9（pivotal weight）** 任务 `t` 的 pivotal weight `w_t = P(任务 t 的结果改变我们的排名)`，由蒙特卡洛模拟估计。直觉：不是所有任务都同等重要；只有“差一点就改变名次”的任务值得优先投入。

**定义 D10（预算分配）** 给定候选技能变体 `i` 的成本 `c_i` 与能力提升 `ΔC_i`，分配预算 `B` 以最大化 `Σ_i ΔP(rank ≤ k | ΔC_i) / c_i` 的近似增益；采用贪心 + 本地搜索，并加“平均分不降”约束。直觉：把算力花在“单位成本最能改变排名”的技能上。

**定义 D11（锦标赛 / 冠军—challenger）** 设当前冠军为 `π_champ`，挑战者为 `π_chal`。在配对 episode 上计算 `Δ = S(π_chal) − S(π_champ)` 的置信下界 `LCB(Δ)`；仅当 `LCB(Δ) > δ`（预注册效应量）时晋升。直觉：内部选型也要有“统计裁判”。

**定义 D12（安全提交策略）** 安全提交策略是一个映射 `F: (obs, health, latency) → {π_main, π_fallback}`；当健康检查失败、延迟超预算、动作离群或 OOD 分数超阈值时切到 `π_fallback`。对任意故障集合 `E`，要求 `E[S | F] ≥ (1−ε) S_main + ε S_fallback − L_tail`，其中 `L_tail` 是尾部损失预算。直觉：回退不是承认失败，而是把无界损失变成有界损失。

```python
# ===== SK-04：排名概率与预算分配 =====
def rank_probability(our_scores, field_scores, k, n_sim=10000, seed=0):
    """our_scores / field_scores: [n_tasks] 的点估计或后验样本。
    返回 P(rank <= k) 的蒙特卡洛估计。"""
    rng = np.random.default_rng(seed)
    wins = 0
    for _ in range(n_sim):
        s_our = simulate_score(our_scores, rng)      # D7: 二项/后验抽样
        s_field = [simulate_score(f, rng) for f in field_scores]
        rank = 1 + sum(s > s_our for s in s_field)
        wins += (rank <= k)
    return wins / n_sim

def pivotal_weights(our_scores, field_scores, k, n_sim=10000):
    """任务 t 的 pivotal weight：该任务结果改变排名的概率。"""
    base = rank_probability(our_scores, field_scores, k, n_sim)
    w = np.zeros(len(our_scores))
    for t in range(len(our_scores)):
        alt = our_scores.copy()
        alt[t] = 1.0 - alt[t]                        # 翻转该任务结果
        w[t] = abs(rank_probability(alt, field_scores, k, n_sim) - base)
    return w / (w.sum() + 1e-12)

def allocate_budget(candidates, B, w, cost):
    """candidates: [(skill_id, task_id, delta_C, cost)]
    贪心：按 (w[task] * delta_C) / cost 排序，再本地搜索。"""
    score = lambda c: w[c.task_id] * c.delta_C / c.cost
    picked, spent = [], 0.0
    for c in sorted(candidates, key=score, reverse=True):
        if spent + c.cost <= B:
            picked.append(c)
            spent += c.cost
    return picked
```

```python
# ===== SK-03：冠军—challenger 晋升 =====
def promote(champ_scores, chal_scores, delta=0.5, alpha=0.05):
    """配对 episode 的分数差；只有置信下界超过 delta 才晋升。"""
    d = np.asarray(chal_scores) - np.asarray(champ_scores)
    lcb = np.quantile(bootstrap_mean(d, n=5000), alpha)   # 单侧下界
    return lcb > delta, lcb

class SafeSubmit:
    def __init__(self, fallback, tau_ms=105):
        self.fallback = fallback
        self.tau_ms = tau_ms
        self.degraded = 0

    def guard(self, a, obs, t0):
        elapsed = (time.perf_counter() - t0) * 1000
        if elapsed > self.tau_ms:
            self.degraded += 1
            return self.safe_extend(a)                 # 末动作短延拓 + 减速标记
        return np.clip(a, self.lo, self.hi)            # 只对残差限幅
```

## 5. 推导（引理 L1–L7）

**引理 L1（计分近共线 ⇒ 单一优化目标）** 若 `step = k·succ + b` 且 `R² ≥ 0.99`，则任何提高 `succ` 的改动在总分排序上不劣于同幅度的 `step` 改动；反之，单独提高 `step` 而不提高 `succ` 的改动收益近似为零。teaser 实测 `k=1.337, b=0.09, R²=0.9955` ⇒ 优化终态成功是充分目标。∎

**引理 L2（有限样本的排名噪声）** 设任务 `t` 的评测为 `X_t ~ Binomial(n_t, p_t)`，总分 `S = (1/T)Σ_t c_t p̂_t`（`c_t` 为成功率与步骤分的合并系数）。则 `Var(S) = (1/T²)Σ_t c_t² p_t(1−p_t)/n_t`。代入 `p_t≈0.3`、`c_t≈2.337`、`T=32`、`n_t=n`，得 `sd(S) ≈ 4.23/√n`（分）。因此 `n=20` 时约 4.2 分，`n=50` 时约 2.7 分，`n=100` 时约 1.9 分；未配对比较下，小于约 `2·sd` 的差距不应被当成真实差异。∎

**引理 L3（尾部风险的期望损失）** 设 N 台真机中一台端口在评测期间故障，且其负责的 episode 覆盖约 `1/N` 的任务；若故障任务记零分，则期望总分损失约 `S̄/N`。取 `S̄≈30`、`N=3`，损失约 10 分；而 teaser 的技能路由 oracle 上界仅 +4.26 分。因此 `S̄/N > oracle_gap` 时，可靠性投入的期望回报高于算法创新。∎

**引理 L4（技能复用的样本效率与负迁移界）** 若技能 `s` 在 `m` 个任务中复用，则其有效训练样本量约为单任务的 `m` 倍，泛化误差上界按 `O(1/√(m n))` 收缩。但若测试任务 `t` 不满足 `I_s`，则负迁移损失上界为 `P(b_s(o) ≥ τ_s | o ∉ I_s) · Δ_loss`；因此必须用 D6 的校准边界把假阳性率压到可接受水平。∎

**引理 L5（能力分解的可识别性）** 若技能链中的每个技能在数据中有可观测的起止信号，且交互项 `ε_t` 的方差远小于技能主效应，则 `log P_t` 对 `log C_{s,t}` 的线性回归系数可识别，且 `C_{s,t}` 的估计在每技能每任务 `n ≥ 200` 时标准误 ≤0.04。若交互项不可忽略，则乘积模型只作为“归因近似”，不能用于精确预测。∎

**引理 L6（逐步减半的选型保证）** 若候选变体的能力排序在评测分布上稳定，且配对比较的噪声有界，则逐步减半以高概率保留真实最优变体；在冠军—challenger 规则下，误晋升概率不超过预注册的 `α`（单侧检验）。若排序不稳定（噪声主导），则算法倾向于不晋升，回到 champion，这正是我们想要的保守行为。∎

**引理 L7（安全回退的损失下界）** 设主策略在健康时的期望分为 `S_main`，回退策略为 `S_fallback`，故障触发概率为 `ε`，则安全提交的期望分至少为 `(1−ε)S_main + ε S_fallback − L_tail`。当 `S_fallback` 是“能跑通的基线”时，尾部损失从“整场零分”变为“有界下降”；因此安全提交层提高了排名概率的稳健性，即使它从不提高健康时的均值。∎

## 9. 风险登记册与剪枝预案

| 风险 | 概率 | 影响 | 对冲 |
|---|---|---|---|
| **竞赛模型建立在占位榜/噪声上** | 高 | 高（资源错配） | teaser 只作结构先验；多先验敏感性分析；预注册“只在稳健决策上执行” |
| **技能切分错误 / 技能过细** | 中高 | 高（负迁移、退化） | 双标注器 + 复用覆盖率约束 + 单技能降级形态 |
| **能力矩阵漂移** | 中 | 中高（路由错配） | OOD 门控 + 置信区间 + 边界回退 |
| **锦标赛过拟合验证集** | 中 | 中（选错冠军） | 留出任务/场景双层切分 + 配对检验 + 预注册效应量 |
| **安全层压低成功率** | 中 | 中 | 只对残差限幅；阈值由数据分布定；真机 A/B 决定启用 |
| **端口/并发/延迟事故** | 中 | 高（直接判失败） | SK-05 健康检查 + 故障注入 + 8 h 压测 + 基线回退 |
| **合规**：技能库被判定“多模型” | 中 | 高（取消成绩） | 提交前书面确认；单 checkpoint 叙事；单技能降级形态实测 |
| **代理评测与真机不相关** | 中 | 中高（浪费迭代） | E715 先行；\|r\|<0.3 触发剪枝 |

**剪枝预案（下一轮起执行）**：
- **必保**：SK-05（安全提交）、SK-08（评估竞技场）——它们决定其他结论是否可信。
- **优先深化**：SK-01（技能库）、SK-02（能力矩阵）、SK-04（排名概率）。
- **条件推进**：SK-03（依赖评估竞技场）、SK-06（依赖 OOD 数据）、SK-07（依赖失败日志）。
- **暂存**：跨 embodiment 技能迁移、在线权重更新、技能自动发现（在合规与统计功效未确认前不进入主线）。
