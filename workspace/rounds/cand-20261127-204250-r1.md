## 1. 直觉与动机（两个灵感的碰撞，加上指标取证）

### 灵感 1（评测指标 → 指标不是用来刷的，是用来做信用分配的）

**直觉**：上一轮我们把「步骤分」当成与成功率并列的第二战场，甚至设计了「安全拿部分分」的策略。但官方规则（F21）写得很清楚：成功率第一主键，步骤分只在成功率打平时才起作用；teaser 数据（F25）更极端——步骤分几乎是成功率的 1.337 倍缩放，两者相关系数 0.998。也就是说，**在这套指标下，「刷步骤分」大概率是伪目标**：你无法靠部分分超过一个成功率更高的模型。真正有价值的不是步骤分的数值，而是步骤分背后的**评分点结构**：每个任务 2–5 个语义里程碑（抓把、挂上、插入、拧开、放入），它们给出了「现在进行到哪一步、下一步该做什么、失败发生在哪一步」的密集监督信号。指标应该当**罗盘**用，而不是当**靶子**刷。

**严谨定义**：设任务 t 有 K_t 个评分点，权重 w_{t,k}（Σ_k w_{t,k}=100），第 r 次执行的累计得分为 P_{t,r}=Σ_k w_{t,k}·1[里程碑 k 达成]；成功率 S_{t,r}=1[全部里程碑达成]。榜单主键为
S = (1/32)Σ_t (1/10)Σ_r S_{t,r}，
tie-break 为
P = (1/32)Σ_t (1/10)Σ_r (P_{t,r}/100)。
teaser 上 P≈α+βS（β≈1.337，R²≈0.995），提出假设 **H1：P 是 S 的单调变换，步骤分不提供独立排序信息**。若 H1 成立，则目标函数退化为「最大化 S」，P 只保留两种用途：(a) 训练期的密集信用分配；(b) 诊断失败阶段（早期失败 vs 末步失败）。若 H1 不成立，则说明真实数据中存在「高部分分、低成功率」的任务，才值得单独优化 P。**在 H1 未用真实 per-episode 数据检验前，不把任何预算押在「刷步骤分」上。**

**反直觉点**：评分点最有价值的时候，不是它被算进分数的时候，而是它被当作「任务状态机的标签」的时候。

### 灵感 2（具身智能大模型 → 模型是商品，指标感知的外壳才是差异）

**直觉**：teaser 里 8 个通用具身模型全部挤在 20.5–29.7 的窄带内，榜首与末位只差 9.2 个百分点；而「每任务取 8 模型最优」的 oracle 是 33.96%，比最佳单模型高 4.26 个百分点（F26）。这说明两件事：第一，**模型架构本身已经不是主要矛盾**，大家都能做到 20–30%；第二，**任务条件化仍有明确上限**，不同任务的最优模型不同。但比赛规则是「单一模型完成全部 32 任务，不允许按任务混用多个模型」（手册 §1.1）。所以正确的具身大模型用法不是「训 32 个模型再路由」，而是：一个共享主干 + 任务条件适配器（LoRA/提示/技能族），推理时只激活一个专家；同时用同一个 VLM 的语义能力把公开评分点解析成检查表，做进度监视与失败恢复。**大模型的价值在于「把评分点变成可执行检查表」，而不是「再大一圈的黑箱」。**

**严谨定义**：策略 π(a|o,l,c)，其中 l 为任务指令，c 为公开评分点检查表。引入隐状态 s_t∈{0,1}^{K_t} 表示里程碑完成情况；策略分解为三部分：(i) 共享动作专家 f_θ；(ii) 任务条件适配器 g_φ(l)（单专家激活或软混合）；(iii) 里程碑监视器 h_ψ(o_t,l)→p(s_t)。单模型合规的判定标准：整个服务只加载一个基座 checkpoint + 一个适配器库，每 episode 只激活一个专家；若组委会把「适配器库按任务切换」解释为多模型，则降级为「单 LoRA + 任务提示」的 I11'。监视器离线训练、推理期冻结，不做在线适应。任务条件化的收益上界可由 teaser 的 per-task oracle 估计，但必须用 bootstrap 给出置信区间，避免被 8 个模型的小样本误导。

**反直觉点**：在「单模型」约束下，提升泛化最便宜的方式可能不是更大的统一模型，而是「共享主干 + 很轻的任务条件化 + 很强的评分点状态机」。

### 灵感 3（指标取证 → 用公开榜单做任务组合，而不是平均用力）

**直觉**：32 个任务对总分的贡献是等权的（每个 1/32），但**可提升空间极不相等**。有的任务 8 个模型都卡在 20% 左右（可能是共同瓶颈），有的任务最好与最差差 25–29 个百分点（说明方法选择很关键），有的任务「部分分很高但成功率低」（说明失败集中在最后一步）。把有限的数据、训练、真机预算平均撒到 32 个任务上，是最差的策略。正确做法是先做**指标取证**：从公开榜单估计每个任务的 regret（最好模型 − 平均模型）、spread（最好 − 最差）、partial gap（步骤分 − 成功率），再乘上「该任务的可迁移性/成本」得到杠杆分，优先投高杠杆任务。**但 teaser 可能只是占位数据，所以本轮的真正产物是「取证协议 + 任务组合优化器」，而不是一张固定的任务排名表。**

**严谨定义**：对任务 t，令 S_{m,t} 为模型 m 的成功率，P_{m,t} 为步骤分。定义
R_t = max_m S_{m,t} − mean_m S_{m,t}（regret，可达上限），
D_t = max_m S_{m,t} − min_m S_{m,t}（spread，方法敏感性），
G_t = mean_m P_{m,t} − mean_m S_{m,t}（partial gap，失败阶段代理）。
暂定杠杆分 L_t = R_t·D_t·(1+G_t/10)/cost_t。对 8 个模型做 bootstrap，得到 L_t 的置信区间；区间跨零的任务不优先。任务组合问题为：在预算约束下最大化 Σ_t ΔS_t，其中 ΔS_t 是干预任务 t 的期望成功率增益；L0 估计 ΔS_t，L2 真机确认。**L_t 只用于排序假设，不用于宣称事实。**

**三者统一**：评测指标回答「优化什么」（成功率第一，步骤分是诊断信号），具身大模型回答「用什么承载」（共享主干 + 任务条件化 + 评分点监视器），指标取证回答「先做哪个任务」（按杠杆分配预算）。本轮结论：**中期胜负手从「模型/数据规模」转向「指标感知的信用分配与任务组合」；success 是主目标，step 是诊断信号，具身大模型的价值在于把评分点变成检查表。**

## 2. 对第 2 轮痛点的增量修订

- P2（泛化缺口）再细化：F24 把每任务的 unseen object 与 human 扰动注记公开到 `info.json`，I1 的考纲卡可以从「5 轴粗粒度」升级为「每任务具体物体/位移/扰动脚本」。
- P5（时间压力）更新：F22 确认 N=10；F23 确认每任务步骤分值。时间预算应按 10 次 × 32 任务重新核算；单任务通道仍只用于调试，不计入榜单。
- P8（示教质量）升级为 **P8'（阶段质量）**：不是整条 episode 等权，而是按评分点阶段加权——抓取/插入/末步放置的帧比接近段更有价值；这直接支撑 I10 的里程碑加权损失。
- **新增 P9（指标伪独立）**：步骤分看起来是第二轴，但在 teaser 上与成功率近乎共线；若真实数据也如此，所有「为部分分优化」的模块都应降级，只保留其作为密集监督/失败诊断的用途。
- **新增 P10（teaser 污染）**：公开榜单被遮罩且可能为占位数据；任何基于它的任务排序、阈值、相关性结论都必须带「未定稿」标签，并用 bootstrap 与小样本修正。

## 3. 研究问题（本轮立项 Q9–Q13，Q1–Q8 保留）

- **Q9（指标可辨识性）**：步骤分与成功率在真实 per-episode 数据上是否独立？H1 是否成立？如果步骤分只是成功率的缩放，官方为何保留它作为 tie-break——是为了区分「同样成功但更高效」还是只是历史遗留？
- **Q10（任务组合）**：在 32 任务等权平均下，如何用公开榜单（含 teaser 不确定性）估计每个任务的边际成功增益，并把数据/训练/真机预算分配到高杠杆任务？如何防止对 8 模型小样本过拟合？
- **Q11（评分点信用分配）**：用公开评分点把示教切成里程碑段后，帧级/段级加权与辅助里程碑损失能否比均匀行为克隆更有效地提升成功率？加权应该加在「高价值段」还是「高失败段」？
- **Q12（单模型任务条件化）**：在「单模型」约束下，任务条件 LoRA/技能族路由能否吃到 teaser 所示的 per-task oracle 上限（+4.26）？合规边界在哪里？负迁移如何用 L0 提前发现？
- **Q13（失败阶段诊断）**：partial gap G_t 能否区分「早期失败（接近/抓取）」与「末步失败（放置/插入/拧开）」？能否据此把 I1（增广）与 I5（恢复示教）路由到正确的任务族？

## 4. 设计原则（新增 PR6–PR8，其余保留）

- **PR6 指标主权律**：成功率是第一主键；步骤分只做 tie-break 与密集诊断。任何模块若以牺牲成功率为代价换取步骤分，默认否决。
- **PR7 任务组合律**：预算按「期望边际成功增益/成本」分配，不按任务数量平均分配；高杠杆任务优先，低杠杆任务只做保底。
- **PR8 单模型合规律**：任务条件化必须是「一个基座 + 一个适配器库 + 单专家激活」，并取得组委会书面确认；未确认前不上计分通道，降级为 I11'（单 LoRA + 任务提示）。
- PR1–PR5 保留（第 1/2 轮 §4）。PR5 数据杠杆律与 PR7 互补：PR5 管「一条数据教什么」，PR7 管「一个任务值多少预算」。

## 6. 本轮最大风险

**一句话**：把被遮罩的 teaser 榜单当作真实评测分布——其 `step≈1.337×success` 的近乎完美线性更像生成脚本的占位数据；若据此做任务配比、阈值校准与「步骤分无用」的结论，可能系统性偏离真实评测，必须等真实 per-episode 数据或官方揭榜后重跑取证协议。

```python
class ScoreStatePolicy:
    def reset(self, first_obs=None):
        self.steps = parse_score_steps(self.instruction)   # 公开 info.json：2–5 步 + 权重
        self.s = [0.0] * len(self.steps)                   # 里程碑完成概率
        self.stall = 0

    def get_action(self, obs):
        chunk = self.vla.propose_chunk(obs, checklist=self.steps)
        if self._should_monitor(obs):
            p = self.monitor(obs, self.steps)              # VLM 隐状态线性头 / 轻量视觉头
            self.s = update_with_hysteresis(self.s, p)     # 多标签 + 滞回
            self.stall = self.stall + 1 if not advanced(self.s) else 0
        if self.stall >= K and failure_risk(self.s) > TAU:
            return self.recover(obs, self.s)               # I5 恢复 / 重试 / 重新接近
        return self.guard_stack(chunk, obs)                # I4/I5 guard 不变

def milestone_weighted_flow_loss(batch, monitor):
```

### 2.3 任务杠杆与组合优化（I8）

```python
def task_leverage(leaderboard, task, cost=1.0):
    s = [m.task_metrics[task].success_rate for m in leaderboard.models]
    p = [m.task_metrics[task].step_score for m in leaderboard.models]
    regret = max(s) - mean(s)
    spread = max(s) - min(s)
    gap = mean(p) - mean(s)
    return regret * spread * (1 + gap / 10) / cost

def bootstrap_leverage(leaderboard, task, n=2000):
    vals = []
    for _ in range(n):
        sample = resample(leaderboard.models)
        vals.append(task_leverage(sample, task))
    return percentile(vals, 5), percentile(vals, 95)   # 区间跨零 → 不优先

def allocate_budget(tasks, budget):
```

## 3. 实验设计（分级消融协议 v3）

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0-指标 | H1 回归/残差/方差分解；32 任务杠杆 + bootstrap；揭榜后重跑 | 离线（CPU） | 若 H1 成立，后续不以步骤分为独立目标；杠杆区间跨零的任务不优先 |
| L0-监视器 | I10 里程碑监视器：AUROC/校准/提前检测失败；不伤标称 | 离线（1 GPU 日/族） | 里程碑 AUROC >0.8；标称任务 stall 误报 <5%；失败检测早于终局 ≥10 步 |
| L0-信用 | 均匀 BC vs 里程碑加权 BC vs 阶段重采样 | 离线（1×24GB） | 留出任务成功率代理 ≥ 基线；高价值段动作误差下降 |
| L0-专家 | I11 技能族 LoRA：leave-one-family-out；路由准确率 | 离线（1×24GB） | 无家族退步；路由准确率 >90%；负迁移任务可被 L0 提前发现 |
| L0-数据 | I2 孪生迁移 + 任务组合权重；I1 各轴剂量-响应 | 离线（免费） | 孪生 Δprog>0 且无家族退步；I1 不可行动作占比 <5% |
| L1 | 2^(k-p)：I10/I11/I1/I9 开关部分析因；guard 栈 3 模块 | 离线 + 少量真机 | 主效应显著的 ≤3 个组合进入 L2 |
| L2 | top 组合真机确认：高杠杆任务优先，≥2 任务 × 各 2 次 | 单任务通道 | 成功率相对基线提升 ≥ 离线预测的 50%；不以步骤分单独判胜 |
| 门禁 | PR4：run_client 全流程 + p99 + 动作健康度 | 本地 stub | 0 拒绝动作、p99 <40ms |

**首批 L2 排队（按 success-first + 杠杆）**：①I10 在 3 个高 G_t 任务（StackCups/PlacePhotoFrames/RemovePinnedNote）+ 2 个低 G_t 任务（PlugInEthernet/Unlock）试点；②I11 在 2 个技能族（抓取放置/插入接触）试点；③I1 的 unseen/human 两轴；④I2 任务组合权重（cap 20%）。每步先看成功率，步骤分只作为同成功率下的 tie-break。
