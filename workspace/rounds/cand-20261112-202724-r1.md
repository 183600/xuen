# 第 62 轮（承接第 61 轮「具身语义进化闭环」ESEC IP-173~182；灵感循环第 8 轮；本轮灵感：「双足机器人」×「续航能力」）

> 第 61 轮把「场景→意图→阻抗→证据」统一进 USR 语义空间，并用 MEL、DMS、SRT-Dual 打通语义流与实时流。但它仍隐含一个强假设：**机器人是插电的固定基座机械臂**。本轮两个灵感词恰好击中这一盲区：**双足**意味着浮动基座、ZMP 平衡与步态流形，**续航**意味着焦耳预算与分钟-小时级长时程规划。二者合流指向一个被忽视的命题——**能量不是执行层的背景常量，而是语义层的一等公民**。

> **第 61 轮遗留的四个局限**：
> 1. **能量盲区**：USR、B_cog5、J_sem_exec 均不含 SoC、功率、热约束；「语义多么正确」与「还能跑多久」完全解耦。
> 2. **形态盲区**：K_safe 的可行集按固定基座机械臂设计，未耦合 ZMP/支撑多边形；单手操作时平衡裕度与阻抗互相挤压。
> 3. **时间尺度断档**：SRT-Dual 只有 10-100Hz 语义流与 1-10kHz 实时流，而续航规划是 0.001-1Hz、分钟-小时级，缺少最慢的一层。
> 4. **计算能量未计价**：MEL 推理耗电可达数十瓦，长时间高频推理会与运动争夺电池；「思考」与「行走」没有统一的焦耳账本。

## 0. 直觉与动机

**灵感 1（双足 × 续航 → 能量-语义统一表征 ESS）**
直觉：第 61 轮把场景、意图、阻抗、证据映射进 USR，却把「还剩多少电、正在以多大功率放电、电池多热」留在门外。可能量恰恰是**所有语义决策的共同约束**：同样的「轻触」意图，在 80% 电量与 8% 电量下应编译成不同的 K_safe 与不同的任务节奏。关键洞见：把能量状态也编码为 `energy_emb ∈ ℝ^d_us`，与 scene/intent/impedance/evidence 共享同一潜在空间，使「语义—能量」成为可联合运算、可对齐、可审计的向量路径。

**灵感 2（双足 → 步态-能量流形 BGEM）**
直觉：轮式底盘的能耗近似与速度线性相关，而双足是**间歇式倒立摆**：每一步都在「受控跌倒」与「能量回收」之间交换动能/势能。因此双足的能耗不是标量，而是定义在**步态流形**上的泛函 `E_gait(g, θ; φ, m, v)`，其中 g 是离散步态（站立/行走/小跑/上下楼梯/深蹲），θ 是连续步态参数（步长、步频、抬脚高度、躯干俯仰），φ 是地形物理属性，m 是负载。关键洞见：**步态选择本身是语义决策**——「够到高处的货架」约束了工作空间，进而约束步态，进而决定能耗；语义、形态、能量在此闭环。

**灵感 3（双足 × 续航 → 信息-能量-速度三元悖论 EIT）**
直觉：电池能量在固定任务时长内是零和的：`E = E_info + E_act + E_balance + E_aux + E_reserve`。让 MEL 跑得更勤（E_info↑）或让机器人走得更快（E_act↑），都会挤压其余项。于是存在一条**帕累托前沿**：语义丰富度 Q、语义频率 f_mel、运动速度 v 三者不能同时无限提升。关键洞见：把「推理频率」当作可交易的能量商品，用 **VOI/焦耳** 而非单纯的 VOI 做准入，才能避免「用 80 瓦的算力去省 20 瓦的步态优化」这种本末倒置。

**灵感 4（双足 × 续航 → 平衡-能量耦合可行阻抗 BECI）**
直觉：单腿支撑去拧阀门时，支撑多边形从双脚缩小到单脚，ZMP 必须留在更小的区域内，踝/髋需要更大恢复力矩，瞬时功率上升、关节发热。也就是说，**阻抗可行集 K_feas 不只是力/位约束，还要同时满足 ZMP 约束、力矩上限与功率/热上限**。关键洞见：把 K_safe 的可行域写成 `K_feas(s) = {K : ZMP(K)∈SP(s)⊕margin, τ≤τ_max, P≤P_cap(SoC,T), F≤μN}`，平衡裕度与能量裕度成为同一约束系统的两个面。

**灵感 5（续航 → 三时间尺度流 TSTF）**
直觉：第 61 轮的双流仍缺最慢的一层。续航规划是**分钟到小时**的问题（走哪条路、用哪种步态、什么时候充电、任务是否降级），语义是**百毫秒**的问题，实时控制是**毫秒**的问题。关键洞见：引入最慢的**能量规划流 EPL（0.1-1Hz）**，输出「能量锚点」（各子系统焦耳配额、功率上限、步态计划、保留电量），语义流只在其配额内推理，实时流只在其功率上限内执行；三层锚点用单调版本号与 TTL 同步，任一上层失联则下层保守回退。

**灵感 6（续航 → 续航感知对话与能量账本 EADP + EL）**
直觉：电量不足不该是「突然关机」，而应是**可协商、可解释、可审计**的过程。对话层应主动说：「剩余电量不足以完成全部 12 个货架，是否改为前 8 个 + 中途充电？」或「是否允许把精度从 ±1mm 放宽到 ±3mm 以省电？」关键洞见：每一次推理、每一次迈步、每一次阻抗维持都写入**能量账本**（按动作分类的焦耳流水），账本根哈希进入**能量证书**，使「为什么这块电池只撑了 40 分钟」可被逐项追溯。

## 1. 形式化定义（增量：定义 173–186）

**定义 173（能量-语义状态 ESS）** 能量语义状态 E = (e_loc, e_man, e_cmp, e_aux, e_thm, soc, T_batt, T_motor) ∈ ℝ⁸，其中 e_* 为最近窗口内各类能耗（J），soc ∈ [0,1] 为荷电状态，T_* 为温度。定义能量编码器 `E_energy: ℝ⁸ → ℝ^d_us`，并入 USR：
- **能量锚点**：`EnergyAnchor_t = (energy_emb_t, soc, soc_forecast(τ,σ), e_alloc, p_cap, gait_plan, version, timestamp)`
- **能量可行性谓词**：`Feasible(e_req, ρ) ⇔ e_req ≤ (1-ρ)·E_cap·soc`，ρ 为保留比例（默认 0.15）
- **能量查询**：`RemainingBudget(category) = e_alloc[category] - ∫ P_category dt`

**定义 174（双足步态-能量流形 BGEM）** 设离散步态集 G = {stand, walk, trot, stair_up, stair_down, squat, one_leg_support}，连续参数 θ ∈ Θ_g ⊂ ℝ^{n_g}。步态流形 `M_g = ⊔_{g∈G} ({g} × Θ_g)`，其上的能量泛函：
```
E_gait(g, θ; φ, m, d) = CoT(g, θ; φ, m) · m · g_acc · d + E_transition(g → g')
CoT = P_mech/(η·m·g_acc·v) + P_balance/(m·g_acc·v) + P_regen_credit
```
其中 φ = (μ_fric, slope, roughness, stiffness) 为地形物理属性，m 为负载，d 为距离，E_transition 为步态切换代价。**步态-阻抗耦合**：`K(g,θ) = K_nom(g) + ΔK(θ)`，即步态改变阻抗可行域与操作工作空间。

**定义 175（信息-能量-速度三元悖论 EIT）** 对固定任务时长 T 与可用能量 E_use = (1-ρ)E_cap·soc：
```
E_use = E_info(f_mel, |MEL|) + E_act(v, g, m) + E_balance(support) + E_aux + E_loss
E_info = ∫ P_compute(f_mel, |MEL|) dt,   E_act = ∫ P_act(v, g, m) dt
```
定义可达集 `A(E_use, T) = {(Q, f_mel, v) : ∃ 策略 s.t. 上式成立 ∧ 约束满足}`，其边界即**信息-能量-速度帕累托前沿**。关键推论：`f_mel` 的边际收益递减而边际能耗近似线性，故存在唯一的能量最优推理频率 `f*_mel = argmax_f VOI(f)/ΔE(f)`。

**定义 176（平衡-能量耦合可行阻抗 BECI）** 在状态 s 下：
```
K_feas(s) = { K=(K_p,K_d,F_max) :
    ZMP(K, s) ∈ SP(s) ⊕ margin_balance,
    τ_joint(K) ≤ τ_max,  ∀j,
    P_joint(K, s) ≤ P_cap(soc, T_batt),  ∀j,
    F_norm ≤ μ_fric·N_normal·(1-margin_slip) }
```
其中 SP(s) 为支撑多边形（单腿支撑时退化），P_cap 由功率预算与热约束共同给出。实时编译问题变为 `K_safe = argmin_K cost(K) s.t. K ∈ K_feas(s) ∩ K_sem`。

**定义 177（三时间尺度流 TSTF）** 系统拆为三层异步流水线：
- **能量规划流 EPL（f_E ∈ [0.1,1] Hz，时域 60-1800 s）**：求解「任务—步态—能量」联合规划 `min Σ E_gait + E_man + E_cmp + E_aux s.t. SoC_end ≥ ρ, deadline, task_quality`，输出能量锚点。
- **语义流 SL（f_S ∈ [10,100] Hz，时域 0.1-1 s）**：MEL + DMS + USR，**仅在 e_alloc[compute] 配额内运行**。
- **实时流 RTL（f_R ∈ [1,10] kHz，时域 1-10 ms）**：EEIS + ERTC + CLEP + 步态/平衡控制器，**仅在 p_cap 与 K_feas 内执行**。
- **同步协议**：能量锚点 version 单调递增；SL/RTL 读取到过期能量锚点时，保留电量自动上浮（`ρ ← ρ·1.1`）、功率上限自动下压（`p_cap ← 0.9·p_cap`）；连续 3 次过期则触发降级阶梯。

**定义 178（七维认知-能量预算 B_cog7 与 PCE++++++）** 在 B_cog5 基础上加入能量与降级：
```
B_cog7 = (B_scene, B_intent, B_ros, B_exec, B_mel, B_usr, B_energy)
B_energy = (E_rem, P_cap, Reserve, T_batt_max, T_motor_max, e_info_quota, degradation_level)
```
**降级阶梯 EDL**：D0 全功能 → D1 MEL 降频 50% → D2 MEL 蒸馏 → D3 关闭语义流、仅用缓存锚点 → D4 步速降 30%、禁用高功率步态 → D5 就近坐下/靠墙并请求充电 → D6 安全停机。每一级声明其**必须保持不变的安全不变量**（平衡、热、ERTC 实时契约）。

**定义 179（焦耳归一化信息价值 VOI-J）** 对动作 a：
```
VOI-J(a) = VOI(a) / max(ΔE(a), ε_E),   ΔE(a) = P_compute·Δt_compute + E_act(a) + E_comm(a)
Admit(a) ⇔ VOI-J(a) ≥ λ_J ∧ ΔE(a) ≤ e_info_quota ∧ degradation_level ≤ max_level(a)
```
**盈亏平衡推理频率**：`f_breakeven = P_compute / (VOI_per_inference / λ_J)`，当 f_mel > f_breakeven 时继续提高频率在经济上不划算。

**定义 180（续航感知对话管理 EADP）** DMS 状态扩展为 `S = (H_diag, b_intent, C_exec, C_pending, U_mel, turn_id, soc_forecast, mission_deadline, reserve)`；动作扩展 `A ⊇ {propose_energy_degrade(q), propose_staged_task(phases), propose_recharge(min), negotiate_quality(Q)}`；奖励扩展：
```
R = 𝕀[complete] - λ_cog·load - λ_safe·risk - λ_lat·latency - λ_E·E_used - λ_T·time_overrun
```

**定义 181（能量账本 EL）** 账本 `L = {entry_i}`，每条 `entry_i = (t_i, action_id, category, ΔE_measured, ΔE_predicted, ΔSoC, evidence_hash, t_batt, t_motor)`。守恒约束：
```
ΔSoC·E_cap = -( Σ_cat ΔE_measured + E_loss ) ± ε_E
```
账本以 Merkle 树累计，`ledger_root = MerkleRoot(L)`，供证书与事后审计。

**定义 182（能量-执行联合证书 J_energy）** 扩展 J_sem_exec：
```
J_energy = (J_sem_exec, e_mission_est, reserve_margin, thermal_margin,
            balance_margin, ledger_root, gait_plan_hash, degradation_level)
Valid(J_energy) ⇔ Valid(J_sem_exec)
                  ∧ reserve_margin ≥ 0
                  ∧ thermal_margin ≥ 0
                  ∧ balance_margin ≥ 0
                  ∧ |ΔSoC·E_cap + ΣE_measured + E_loss| ≤ ε_E
```

**定义 183（能量感知具身语义闭环 E²SEC）** 在 ESEC 外层包一层能量规划，三层闭环：
```
E²SEC(M, mission, terrain_phi):
  # 慢：能量规划流（0.1-1Hz）
  anchor_E ← EPL.solve(mission, M.soc, terrain_phi)
  M.e_alloc ← anchor_E.e_alloc; M.p_cap ← anchor_E.p_cap
  # 中：语义流（10-100Hz），受 e_alloc[compute] 约束
  if VOI-J(MEL.infer) ≥ λ_J and within quota:
      φ_phys, z_scene, π_intact, U_mel ← MEL.infer(...)
      M.energy_emb ← E_energy(M.soc, P_act, P_cmp, T_batt, T_motor, ...)
      a_diag ← DMS.step(U_mel, soc_forecast=anchor_E.soc_forecast)
  # 快：实时流（1-10kHz），受 p_cap 与 K_feas 约束
  K_safe ← BECI.compile(delta_f_req, φ_phys, anchor_E.p_cap, support_state)
  dispatch(K_safe); EV_exec ← wait_contact()
  M.ledger.append(measure_energy(EV_exec, K_safe))
  M.J_energy ← build_energy_cert(M.J_sem_exec, M.ledger, anchor_E)
  return M, K_safe, EV_exec, M.J_energy
```

**定义 184（任务能量契约 MEC）** 契约 `C_E = (E_cap, soc_0, T_deadline, Q_req, ρ_min, T_batt_max)`；可行性：
```
Feasible(C_E) ⇔ E_required(Q_req, T_deadline, gait_plan) ≤ (1-ρ_min)·E_cap·soc_0
```
若不可行，则必须选择一项：降低质量 Q_req、放宽时限 T_deadline、减少工作量、或插入充电；不存在「既不降级又按时完成」的第四种选择（**能量三选一定理**）。

**定义 185（零样本步态能量泛化 EZGP）** 对未见地形 φ_new ∉ Φ_train，由 MEL 物理先验 φ_phys 与 BGEM 成本模型外推：
```
Ê_gait(g,θ; φ_new) = CoT_θ(g; φ_phys) · m · g_acc · d
泛化目标：|Ê_gait - E_gait| / E_gait ≤ δ_cot（实测目标 ≤ 15%）
```

**定义 186（能量锚点协议 EAP）** 与 SACP 对偶：
- **写入原子性**：CAS 写 `(e_alloc, p_cap, soc_forecast, gait_plan, version, ts, checksum)`，version 64 位单调。
- **新鲜度**：EPL 周期 T_E = 1/f_E，若 `now - ts > 3T_E` 视为过期，触发保留电量上浮与功率下压。
- **预测不确定性**：`soc_forecast = (μ_soc, σ_soc)`；若 `σ_soc > σ_max`（默认 0.05），RTL 采用 `μ_soc - 2σ_soc` 的悲观值。
- **回滚**：连续 3 次过期 ⇒ 回退到「上一稳定能量锚点 + 最保守功率上限」。

### IP-183 ESS（能量-语义状态）

```python
class EnergySemanticState:
    def __init__(self, d_us=256, e_cap_kwh=1.0, soc_reserve=0.15):
        self.d_us, self.e_cap, self.soc_reserve = d_us, e_cap_kwh, soc_reserve
        self.energy_encoder = EnergyEncoder(d_us)   # ℝ^8 -> ℝ^d_us
        self.soc_forecaster = SoCForecaster()       # TCN, horizon 60-1800s

    def encode(self, soc, p_act, p_cmp, p_aux, p_thm, t_batt, t_motor):
        x = torch.tensor([soc, p_act, p_cmp, p_aux, p_thm, t_batt, t_motor])
        return self.energy_encoder(x)

    def feasible(self, e_req, reserve=None):
        rho = self.soc_reserve if reserve is None else reserve
        return e_req <= (1 - rho) * self.e_cap * self.soc

    def forecast(self, horizon_s, gait_plan):
        mu, sigma = self.soc_forecaster(self.soc, horizon_s, gait_plan)
        return mu, sigma
```

### IP-184 BGEM（步态-能量流形）

```python
class GaitEnergyManifold:
    def __init__(self, gaits=('stand','walk','trot','stair','squat','one_leg')):
        self.gaits = gaits
        self.cost_model = GaitCostNet()   # (g, θ, φ, m) -> CoT

    def energy(self, g, theta, terrain_phi, payload, distance):
        cot = self.cost_model(g, theta, terrain_phi, payload)
        return cot * payload * 9.81 * distance + self.transition_cost(g)

    def select(self, task_req, terrain_phi, soc, deadline, p_cap):
        best = None
        for g in self.gaits:
            for theta in self.grid(g):
                if not self.workspace_ok(g, theta, task_req):
                    continue
                e = self.energy(g, theta, terrain_phi, task_req.payload, task_req.dist)
                if self.time_est(g, theta, task_req.dist) > deadline:
                    continue
                if not self.power_ok(g, theta, p_cap):
                    continue
                if best is None or e < best[0]:
                    best = (e, g, theta)
        return best   # (energy_J, gait, theta) 或 None
```

### IP-187 TSTF（三时间尺度流）

```python
class TripleTimescaleFlow:
    """
    EPL : 0.1-1 Hz  | horizon 60-1800 s | gait + task + energy planning
    SL  : 10-100 Hz | horizon 0.1-1 s   | MEL + DMS + USR
    RTL : 1-10 kHz  | horizon 1-10 ms   | EEIS + ERTC + balance
    """
    def __init__(self, epl, sl, rtl):
        self.epl, self.sl, self.rtl = epl, sl, rtl
        self.energy_anchor = None
        self.semantic_anchor = None

    def energy_loop(self, mission, soc, terrain_phi):
        plan = self.epl.solve(mission, soc, terrain_phi)
        self.energy_anchor = EnergyAnchor(
            plan, version=next_version(), ts=now())
        self.sl.set_energy_quota(plan.e_alloc['compute'])
        return self.energy_anchor

    def semantic_loop(self, obs):
        if self.sl.energy_quota_exhausted():
            return self.sl.degrade()
        return self.sl.step(obs, self.energy_anchor)

    def realtime_loop(self, cmd):
        cap = min(self.energy_anchor.p_cap, thermal_cap())
        return self.rtl.step(cmd, power_cap=cap,
                             balance_margin=self.energy_anchor.balance_margin)
```

### IP-188 PCE++++++（七维预算 + 降级阶梯）

```python
class CognitiveEnergyBudget:
    DEGRADE = ['D0_full','D1_mel_halved','D2_mel_distill',
               'D3_semantic_off','D4_slow_gait','D5_sit_recharge','D6_safe_stop']

    def __init__(self, e_cap_kwh, soc_reserve=0.15, lambda_J=1.0):
        self.E_cap = e_cap_kwh * 3.6e6
        self.reserve = soc_reserve
        self.lambda_J = lambda_J
        self.level = 0
        self.spent = {c: 0.0 for c in ('locomotion','manipulation','compute','aux','thermal')}

    def voi_j(self, action, delta_energy):
        return action.voi / max(delta_energy, 1e-6)

    def admit(self, action, delta_energy):
        return (self.voi_j(action, delta_energy) >= self.lambda_J
                and delta_energy <= self.e_info_quota
                and self.level <= action.max_level)

    def spend(self, category, joules, soc):
        self.spent[category] += joules
        if soc < self.reserve:
            self.level = min(self.level + 1, len(self.DEGRADE) - 1)

    def invariants_hold(self, balance_ok, thermal_ok, ertc_ok):
        return balance_ok and thermal_ok and ertc_ok
```

### IP-190 EADP（续航感知对话）

```python
class EnergyAwareDialogue:
    def propose(self, soc_forecast, mission, quality_req):
```

1. **能量账本可靠性**：任一能量证书的 `ledger_root` 可逐项复算，误差 ≤ ε_E；不可伪造「未消耗的焦耳」。

### IP-186 BECI（平衡-能量耦合阻抗）

```python
class BalanceEnergyCoupledImpedance:
    def __init__(self, robot_model, power_model):
        self.model, self.power = robot_model, power_model

    def feasible_set(self, s, soc, t_batt, support):
        Ks = self.model.nominal_impedances()
        feasible = []
        for K in Ks:
            zmp = self.model.zmp(K, s)
            if zmp not in self.model.support_polygon(support):
                continue
            if not self.model.torque_ok(K, s):
                continue
            if self.power.peak(K, s) > self.power.cap(soc, t_batt):
                continue
            if self.model.slip_ok(K, s):
                feasible.append(K)
        return feasible

    def compile(self, delta_f_req, phi_phys, p_cap, support, s, soc, t_batt):
        Ks = self.feasible_set(s, soc, t_batt, support)
        if not Ks:
            return self.safe_stop_pose(s)          # 可行集空 -> 安全停机
        Ks = [K for K in Ks if self.power.peak(K, s) <= p_cap]
        return min(Ks, key=lambda K: self.cost(K, delta_f_req, phi_phys))
```

```python
class CognitiveEnergyBudget:
    DEGRADE = ['D0_full','D1_mel_halved','D2_mel_distill',
               'D3_semantic_off','D4_slow_gait','D5_sit_recharge','D6_safe_stop']

    def __init__(self, e_cap_kwh, soc_reserve=0.15, lambda_J=1.0):

        self.reserve = soc_reserve
        self.lambda_J = lambda_J

        self.e_info_quota = 0.0
        self.spent = {c: 0.0 for c in ('locomotion','manipulation','compute','aux','thermal')}

    def voi_j(self, action, delta_energy):
        return action.voi / max(delta_energy, 1e-6)

    def admit(self, action, delta_energy):
        return (self.voi_j(action, delta_energy) >= self.lambda_J
                and delta_energy <= self.e_info_quota
                and self.level <= action.max_level)

        self.spent[category] += joules
        if soc < self.reserve:
            self.level = min(self.level + 1, len(self.DEGRADE) - 1)

    def invariants_hold(self, balance_ok, thermal_ok, ertc_ok):
        return balance_ok and thermal_ok and ertc_ok
```

```python
def voi_j_admission(action, energy_model, budget, lambda_J):
    delta_e = (energy_model.compute_watts(action) * action.latency_s
               + energy_model.actuation_joules(action)
               + energy_model.comm_joules(action))
    if delta_e == 0:
        return True, 0.0
    score = action.voi / delta_e
    admit = (score >= lambda_J
             and delta_e <= budget.e_info_quota
             and budget.level <= action.max_level)
```

```python
    def append(self, action_id, category, e_meas, e_pred, dsoc, evidence, t_batt, t_motor, zmp_margin):
        self.entries.append(dict(t=now(), action_id=action_id, cat=category,
                                 e_meas=e_meas, e_pred=e_pred, dsoc=dsoc,
                                 evidence_hash=hash(evidence), t_batt=t_batt, t_motor=t_motor))
        self.spent[category] += e_meas
        self.T_max = max(self.T_max, t_batt, t_motor)
        self.zmp_margin_min = min(self.zmp_margin_min, zmp_margin)

    def conserved(self, loss_j, eps=0.01):
        lhs = sum(self.entries[-1]['dsoc'] for _ in [0])  # 由调用方传入 ΔSoC 总和
        return abs(lhs * self.e_cap + sum(self.spent.values()) + loss_j) <= eps * self.e_cap

    def merkle_root(self):
        return merkle(self.entries)
```

```python
    }
```

```python
def E2SEC(M, mission, terrain_phi):
    # 慢：能量规划流（0.1-1Hz）
    anchor_E = M.epl.solve(mission, M.soc, terrain_phi)
    M.e_alloc, M.p_cap = anchor_E.e_alloc, anchor_E.p_cap

    # 中：语义流（10-100Hz），受 compute 配额与 VOI-J 准入约束
    admit, score = voi_j_admission(M.next_mel_action, M.energy_model, M.budget, M.lambda_J)

    else:

        a_diag = M.dms.degrade()

    M.J_energy = build_energy_certificate(cert_sem, M.ledger, anchor_E.soc_forecast, anchor_E.gait_plan)
```

## 3. 数值示例：一次 2 小时任务的能量账本

设电池 `E_cap = 1.0 kWh`，保留 `ρ = 15%`，可用能量 `E_use = 850 Wh`；任务 120 min，负载 5 kg。

| 类别 | 功率（全 MEL） | 时长 | 能量 | 功率（VOI-J） | 能量 |
|---|---|---|---|---|---|
| 行走（walk, 0°) | 350 W | 80 min | 467 Wh | 350 W | 467 Wh |
| 站立平衡 | 120 W | 40 min | 80 Wh | 120 W | 80 Wh |
| 操作（阻抗维持） | 100 W | 30 min | 50 Wh | 100 W | 50 Wh |
| 计算（MEL） | 80 W | 120 min | 160 Wh | 25 W | 50 Wh |
| 热管理 | 15 W | 120 min | 30 Wh | 15 W | 30 Wh |
| 损耗（≈10%） | — | — | 79 Wh | — | 68 Wh |
| **合计** | | | **866 Wh** | | **745 Wh** |

- 全 MEL 场景 `866 Wh > 850 Wh` ⇒ **MEC 判定不可行**，必须降级或充电。
- VOI-J 将 MEL 从 10Hz 全模态降到事件触发 + 蒸馏后，计算能量 160→50 Wh，总量 745 Wh，**转为可行**，且任务成功率仅下降 ≤2%（E206 目标）。
- 若再用 BGEM 选择小跑 + 下坡回收，行走能耗可再降 8–12%（≈40–55 Wh），为充电或额外操作留出裕度。
- 该示例说明：**续航的第一杠杆往往不是电池，而是「推理频率 × 功率」与「步态 × 地形」**。

## 4. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| ESS | O(d_us) 编码 | O(d_us)+O(H) | SoC 预测 RMSE ≤ 3%（1σ） |
| BGEM | O(\|G\|·\|Θ\|·d) | O(\|G\|·\|Θ\|) | 能耗预测 MAPE ≤ 10% |
| EIT | O(1) 预算恒等式 | O(1) | 帕累托界误差 ≤ δ_cot+δ_voi |
| BECI | O(n_joint) QP | O(n_joint²) | K_safe∈K_feas，ZMP 违规=0 |
| TSTF | 0.1-1Hz / 10-100Hz / 1-10kHz | 锚点 ~1MB | RTL 不阻塞>1ms；能量锚点新鲜度≥99% |
| PCE++++++ | O(1) | O(1) | 降级 100% 正确，安全不变量保持 |
| EL/J_energy | O(1) 追加 / O(logN) 根 | O(N) | 守恒误差≤1%，证书通过率≥99.9% |

**正确性定理（E²SEC-Complete）**：在 A61–A70 之上补充
**(A71)** 账本守恒：`|ΔSoC·E_cap + ΣE_meas + E_loss| ≤ ε_E`；
**(A72)** SoC 预测校准：`P(|SoC_true-μ_soc| ≤ 3σ_soc) ≥ 0.95`；
**(A73)** BGEM 域随机化误差 ≤ δ_cot；
**(A74)** BECI 可行集在标称接触邻域非空且凸，ZMP 精确；
**(A75)** EAP 64 位单调 + CAS 原子 + 无撕裂读；
**(A76)** EDL 每级保持平衡/热/ERTC 不变量；
**(A77)** VOI-J 能量估计相对误差 ≤ δ_voi。

则：
1. **账本可靠性**：`ledger_root` 可逐项复算，误差 ≤ ε_E；无法伪造未消耗焦耳。
2. **任务能量可行性**：若 `Feasible(C_E)` 且扰动在 A72/A73 置信界内，则 `soc_end ≥ ρ_min`；否则 EDL 必触发且不违反 A76。
3. **平衡-能量安全**：`K_safe∈K_feas ∧ P≤p_cap ⇒ ZMP∈SP ∧ τ≤τ_max`；单腿操作不因省电牺牲平衡裕度。
4. **三元悖论界**：固定 `(E_use,T)` 下，`(Q,f_mel,v)` 不可超出 `∂A(E_use,T)` 超过 `δ_cot+δ_voi`。
5. **降级单调安全**：D0→D6 语义能力单调减弱、安全不变量单调保持，无「越降级越危险」的转移。
6. **端到端增益上界**：相对第 61 轮，续航提升 ≤ `ΔE_compute/E_total + ΔE_gait/E_total`，分别由 VOI-J 与 BGEM 兑现。

## 6. 本轮最大风险

**一句话**：若 BGEM 的 CoT 模型在上下楼梯、负载突变或低摩擦地面上存在系统性 sim2real 偏差，或 SoC 预测在低温/电池老化下偏离悲观界，能量规划流将签发**过度乐观的续航契约**，使机器人在「语义自信、步态优雅」的表象下于任务中途断电，甚至因省电策略压缩平衡裕度而摔倒；必须以「硬件在环在线 CoT 校准 + SoC 悲观置信界 + BECI 平衡硬约束优先于能量软约束 + EDL 逐级安全不变量验证」构成能量安全护栏，确保省电永不跨越平衡与实时安全红线。
