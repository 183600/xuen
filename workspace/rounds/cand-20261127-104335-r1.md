# 灵感驱动研究循环 · UniBot 创新点研究 第 3 轮；本轮灵感：「轻量化结构」×「比赛策略」

> 承接 v1.1（I1–I9）。前两轮一直在做加法（数据引擎、检索、合成示教）；本轮做减法：把「轻量化结构」读成**系统与决策的减法原则**，把「比赛策略」读成**有限预算下的期望分数组合优化**。纪律不变：先核实事实再立论，每个创新点过「计分轴对齐、单模型边界、部署预算」三道闸；清单只做增量深化与修剪，本轮首次执行明确裁撤。

## 0. 赛事核实与承重假设（检索日期 2026-11-27，桌面复核）

F1–F19 沿用；榜单仍「即将发布」（F7/F19 复核无变化），本轮不新增外部事实。为保持严谨，明确区分「事实」与「策略假设」——本轮策略模型依赖四条承重假设，任一被证伪都必须重算 ROI：

| # | 承重假设 | 依据 / 状态 | 若证伪的后果 |
|---|---|---|---|
| A1 | 总分 = 32 任务等权平均（单模型平均分，P1） | 手册口径待原文复核 | 改为难度加权后，ROI 排序需重排，救援带可能移向高权重任务 |
| A2 | 每任务分数是**里程碑阶梯**（得分点制，F17），非连续 | F17 已证步骤分制 | 「救援带命题」退化为普通边际收益，但仍成立 |
| A3 | 每任务评测重复 m_i 小（2/10），单次方差大 | F2 口径 | 降方差（轻量化/护栏）的期望收益被低估 |
| A4 | 「单模型」边界禁止多专家并行路由（PR2） | 待组委会书面确认 | 若允许，I10 可改为更激进的 MoE 蒸馏；确认前按禁止处理 |

一条被前两轮忽略的成本事实：**创新点本身有「维护税」**。每个推理期模块都要过 PR4（延迟/动作健康度）并在 N 端口下做状态隔离；9 个模块的交叉验证与组合消融成本随数量超线性增长（I8 已见组合爆炸）。比赛策略的第一性原理不是「还能加什么」，而是「哪几件事的期望分数/成本最高」。

## 1. 直觉（先给画面，再给定义）

**直觉 1（轻量化结构 → 赢家是「最小充分系统」，不是「最强模型」）**
画面：一支队伍把 9 个模块全塞进推理链，p99 从 35ms 涨到 70ms，N=4 端口开始排队，评测器记录到延迟抖动与动作异常，可信度条款直接扣分——他们不是输给精度，是输给结构重量。
直觉：VLA 比赛的部署预算是 15Hz≈66ms/步（F12），这是**硬约束**，不是优化目标。轻量化的正确读法有三层：(a) **模型轻**——动作头蒸馏/结构化剪枝/量化，把单步压到 p99<40ms，留安全余量；(b) **系统轻**——把 I3/I4/I5 的多个推理期守卫合并成一个 <5ms 的统一护栏，减少状态与故障面；(c) **决策轻**——砍掉高成本低期望的 I7。反直觉点：**轻量化不是为了「省」，而是把省下的延迟/算力/人力换成「更多端口 × 更多重复 × 更低方差」——在阶梯计分里，方差下降本身就是涨分。**

**直觉 2（比赛策略 → 这是一道带预算的背包题，不是「谁点子多」的竞赛）**
画面：32 个任务、每任务 100 分、总分取平均。甲队在 1 个任务做到 95 分、其余 31 个 40 分，平均 41.7；乙队每个任务都 45 分，平均 45。乙赢，且甲多花的力气几乎全浪费。
直觉：比赛策略要显式建模三件事：(a) **任务经济学**——每个任务的当前期望分 μ_i、方差 σ_i²、提升成本 c_i、是否处于「救援带」；(b) **组合分配**——按 ROI=Δμ/c 在预算约束下选子集，而不是按「创新点编号」平均用力；(c) **提交节奏**——永远保留一个已验证的安全基线 S，候选 C 只有过 PR4+L2 才晋升。反直觉点：**阶梯计分下，最该投入的不是最差任务，也不是最好任务，而是「卡在下一级台阶边缘、成功概率≈0.5」的任务（救援带）；而全局可靠性投入应均摊到所有 p≈0.5 的任务上。**

**直觉 3（两者统一 → 轻量化是策略的乘数，策略是轻量化的判据）**
轻量化回答「如何用更少的结构买更大的行动空间」，比赛策略回答「把行动空间花在哪」。统一为一个对象：**每单位成本的期望分数增益（ROI）**。轻量化把成本 c 打下来、把可靠性 p 提上去；策略用 ROI 决定保留哪些创新点。**本轮结论：从中期开始，胜负手从「数据引擎」转向「组合管理」——把 v1.1 的 9 点清单压成 5 个核心 + 3 个条件项 + 1 个明确裁撤，并让每个保留项都能报出自己的 ROI。**

## 2. 严谨定义（把直觉钉死）

记任务 i∈[32]，评测重复 r=1..m_i，单次步骤分 s_{i,r}∈[0,100]，总榜分

S = (1/32) Σ_i (1/m_i) Σ_r s_{i,r}.  （A1；若官方加权则替换为 Σ_i w_i s_i，Σw_i=1）

**定义 1（任务经济状态）** 任务 i 的状态为四元组
E_i = (μ_i, σ_i², c_i, b_i)，
μ_i=E[s_i] 为当前期望分，σ_i² 为单次方差，c_i 为把 μ_i 提升 1 分的边际成本（统一折算为「GPU·小时 + 人日 + 真机槽」），b_i∈{0,1} 表示是否处于救援带。救援带定义为 p_i∈[p_lo,p_hi]（默认 [0.2,0.6]），p_i 为达成下一里程碑的概率。

**定义 2（ROI 与背包）** 候选行动 a（某创新点的一次剂量，或某任务的一次专项）有成本 c_a>0、期望增益 Δμ_a，以及与其它行动的协同项 γ_{a,a'}（数据引擎×蒸馏互补为正，护栏×检索替代为负）。组合选择解

max_{x∈{0,1}^n}  Σ_a x_a Δμ_a + Σ_{a<a'} x_a x_{a'} γ_{a,a'}
s.t.  Σ_a x_a c_a ≤ B,   x_a = 0 若 a 未过 PR4 门禁。

n≤15，用整数规划精确解；每轮重解一次。

**定义 3（救援带命题）** 设任务 i 达成下一里程碑的概率为 p_i，可靠性投入使 p_i → p_i + δ·p_i(1−p_i)（logistic 响应），里程碑价值 V_i。则总期望增益

ΔS = (δ/32) Σ_i V_i · p_i(1−p_i)。

因 p_i(1−p_i) 在 p_i=0.5 取最大：**可靠性/轻量化预算应优先投向 p≈0.5 的任务；能力型投入（新技能、新数据）应投向 p≈0 的任务；p≈1 的任务只做回归测试，不再投入。** 这解释了为什么「平均用力」和「只救最差」都次优。

**定义 4（轻量化约束）** 学生模型 θ_s 满足

min_{θ_s}  E[ D(π_{θ_t}(·|o) ‖ π_{θ_s}(·|o)) + λ‖a_t−a_s‖² ]
s.t.  p99(L(θ_s)) ≤ L_max ≈ 40ms（15Hz 的 60% 安全裕度），Params(θ_s) ≤ ρ·Params(θ_t)。

轻量化的产出不是「更小」，而是三份可分配资源：
R1 = L_max − p99(L(θ_s))（延迟余量 → 更多端口 / 更大 chunk），
R2 = 释放的显存与算力（→ 更多重放与合成示教），
R3 = 方差下降 Δσ²（→ 救援带 p_i 更稳）。
**命题：R1+R2+R3 的期望分数价值 ≥ 蒸馏精度损失，当且仅当救援带非空（Σ_i 1[b_i=1]>0）。** 若所有任务都已 p≈1 或 p≈0，轻量化只值回延迟保险。

**定义 5（提交状态机）** 维护两个 checkpoint：安全基线 S（最近一次通过 PR4 全流程 + L2 的版本）与候选 C。晋升规则

C→S  iff  PR4=pass ∧ L2增益 ≥ 离线预测的 50% ∧ 无任务家族退步。

任何时刻 C 异常则回滚 S。**榜单存在时，S 是「不被清零」的保险，C 是「争排名」的期权；没有 S 的 C 是裸奔。**

## 3. 对 v1.1 痛点的增量修订

- P1（弱任务支配）：从「补弱任务」精确化为「补救援带任务」；p≈0 的任务先修可修性，不修绝望任务（投入产出比最低）。
- P2（泛化缺口）：增广是全局「抬地板」，I1 保留但改为轻量增广（去掉昂贵分割/inpainting，保留几何+光度+背景替换），成本降一档。
- P5（时间压力）：轻量化直接买回时间预算；短 chunk 只用于接触窗（继承 I4）。
- P6（部署风险）：从「低延迟」升级为「延迟保险」——p99<40ms 是硬门禁，不是 KPI。
- P7（先手窗口）：先手优势的正确用法不是「多做创新点」，而是「更早进入 L2 验证循环」；轻量化让 L0/L1 迭代更快。
- **新增 P11（组合爆炸 / 维护税）**：创新点数量本身是成本；9 个模块的交叉验证与状态隔离成本超线性，必须裁撤。
- **新增 P12（方差未计价）**：前两轮只优化均值 μ，未把 σ² 纳入目标；小样本评测下降方差是免费的期望收益。

## 4. 研究问题（本轮 Q9–Q11，Q1–Q8 保留）

- **Q9（轻量化的可分配收益）**：蒸馏/剪枝/量化在 15Hz 预算下释放的 R1/R2/R3，能否在救援带任务上转化为可测的期望分增益？精度损失与延迟收益的交换曲线在哪一档饱和？
- **Q10（ROI 估计的可信度）**：任务级 Δμ 与 c 的估计误差多大时，背包解开始劣于「均摊」基线？需要多少 L0/L1 样本才能让 ROI 排序稳定？
- **Q11（提交节奏）**：在榜单延迟/不公开的条件下，S/C 双轨 + 救援带优先的提交策略，相对「每轮全量替换」的期望排名增益是多少？回滚阈值如何设？

## 5. 设计原则（新增 PR6/PR7，其余保留）

- **PR6 减法优先律（lightweight-first）**：新增任何推理期模块前，先证明「不加模块、只做轻量化/参数调整」达不到同等增益；能合并的守卫必须合并；每个保留模块必须给出 <5ms 延迟预算与独立回滚开关。
- **PR7 预算守恒律**：任何创新点的投入必须从其它项预算中扣除；清单总量以「核心≤5、条件≤3」为上限，超出即裁撤最低 ROI 项。
- PR1–PR5 保留。

## 1. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I1 v3 轻量化考纲增广引擎 ★★★★
- **动机**：计分的 320 次真机评测每次都在 5 轴上偏离训练分布（P2/F2），泛化缺口是全局乘性损失；但 v2 的分割/inpainting 增广成本高、易引入伪影。
- **本轮变化（轻量化）**：保留「考纲卡」思想，但增广算子降为三类廉价操作——①几何（平移/旋转/尺度，只做物理可行范围内）、②光度（亮度/色温/对比度/噪声）、③背景替换（纯色/纹理贴图，不做物体级 inpaint）。昂贵的外观重绘降为条件项，仅在 L0 证明某任务对外观极敏感时启用。
- **与现有方案差异**：盲目增广队伍用无校准随机化；v2 用重增广但成本高；v3 用**考纲校准 + 廉价算子**，把成本压到 1/3 而保留大部分抬地板效应。
- **技术可行性**：高。考纲卡半自动（LLM 解析 wiki + 人工校对，10 分钟/任务 × 32）。
- **所需资源**：1×24GB GPU；无额外分割模型；磁盘增量 <0.5TB。
- **落地步骤**：①32 张考纲卡；②实现三类廉价算子；③L0 剂量-响应（考纲内/边缘/外三档）；④按任务族定档；⑤仅在 L0 提示敏感时升级到外观重绘。
- **风险**：廉价算子覆盖不到「未见物体外观」轴（缓解：该轴交给 I9 检索与 I2 孪生语料）；位置重拼接物理不可行（保留 v2 判据：不可行动作占比 >5% 即降级为平移不变）。

### I2 v3 轻量化数据配方：孪生 top 子集 + 质量加权 ★★★★★
- **动机**：单模型平均分被最弱任务支配（P1）；示教语料与质量双重浪费（P8）；但 v2 的 1–2TB 孪生全量下载与 8×A100 上限违背轻量化。
- **本轮变化（轻量化配方）**：三件事。
  1. **孪生 top 子集**：只下载与 32 考题相似度 s≥0.7 的孪生任务，且每个考题最多 3 个孪生源；按「相似度 × eps 数 × 技能覆盖」排序，先下 top-10 数据集做 L0，正迁移再扩。
  2. **loader 加权 patch（保留）**：官方 ConcatDataset 按样本数比例混采、配置 weight 不生效（F11）→ patch 采样器：32 考题权重 1.0、孪生 0.3–0.5·s、远任务 0.05。
  3. **质量加权（保留）**：per-episode 质量分 = 进度效率 × 平滑度 × 成功裕度；剪最差 10%，软下限 0.2。
- **与现有方案差异**：全量混训把容量与磁盘浪费在已会/低质/远任务；v3 用「先小后大、按 ROI 扩容」的数据配方。
- **技术可行性**：高（frozen-VLM/LoRA 单卡起步，F11）。
- **所需资源**：首轮孪生 top-10 ≈100–300GB（非 1–2TB）；32 考题 ≈2TB（已有）；训练 1×24GB 起步。
- **落地步骤**：①孪生表全 32 项（LLM 初筛 + 人工校对）；②top-10 下载；③loader patch + 单测（batch 内任务频率验证权重）；④首轮共训（32 全量 + top-10 孪生 + 质量加权）；⑤家族级 L0 正/负迁移，正迁移再扩到 top-3/考题。
- **风险**：负迁移（孪生动态相反，如 ZipUp↔Unzip 受力方向）——缓解：家族级 L0、低权重起步、退步即裁剪；相机配置不一致——先抽样核对 4 相机命名/分辨率。

### I5 v3 救援带合成恢复示教 ★★★

- **与现有方案差异**：别人把延迟当 KPI 优化；本点把延迟当**硬门禁 + 可分配资源**（R1）。

### I8 v3 分级消融 + ROI 置信区间注册表（= I11 的决策引擎）★★★★★
- **动机**：真机通道稀缺 + 待验证组合爆炸（P7/P11）；v2 只做分级消融，未把结果转成「该不该投入」的决策。
- **本轮变化**：在 L0/L1/L2 之上加一层**ROI 估计与不确定性**：
  - L0 in-silico（免费）：I1 增广轴剂量、I2 孪生正/负迁移、I5 合成质量、I9 误检索、I10 学生精度损失；代理指标 = Δprog、Δact、Δkp。
  - L1 分数因子（低真机）：2^(k-p) 筛主效应。
  - L2 真机确认（稀缺）：只测 top 2–3，每候选 ≥2 任务 × 2 次。
  - **ROI 注册表**：每个行动记录 (Δμ̂, bootstrap 95% CI, c, 任务族)，输出 ROI 点估计与区间；**裁撤规则：只有 ROI 上界仍低于阈值时才裁撤**（避免因噪声误杀）。
- **技术可行性**：高（L0 纯离线）。
- **所需资源**：代理指标 + bootstrap 1 人周；注册表 = 表格 + 评测脚本。
- **落地步骤**：①代理指标；②注册表 schema；③首个用例 = I2 孪生 top-10 扩容决策；④I10 蒸馏前后 Δμ 对比；⑤每轮重解 ROI 背包。
- **风险**：离线代理与真机相关建立慢（缓解：先用 3–4 个已知真机结果回填；相关性 >0.6 的指标才可单独准入 L2）。

### I9 v3 轻量 reset 检索类比（条件保留）★★★

- **与现有方案差异**：纯通才策略靠平均化覆盖；本点用检索后类比，零权重更新，PR2 合规（服务内组件）。
- **技术可行性**：中-高。嵌入库一次性离线构建（32 任务 + 110 语料首帧），1 GPU 日。
- **所需资源**：FAISS 索引 + 1 人周工程；无每步成本。
- **落地步骤**：①首帧开放词汇检测裁剪物体块；②嵌入 + 索引；③动作先验参数化；④reset 检索 + 软注入；⑤L0 验证不伤标称场景，再真机抽测。

### I10 轻量化推理结构（新）★★★★★
- **动机**：15Hz 硬预算下，模型重量直接决定端口数、重复次数与延迟风险（P6/P12）；前两轮的增益都建立在「推理还能塞进去」的隐含假设上。
- **与现有方案差异**：别人靠换更大模型涨点；本点在**单模型边界内**做「蒸馏 + 结构化剪枝 + 量化」，把重量换成可分配的延迟/算力/方差资源（定义 4 的 R1/R2/R3）。
- **技术方案**：
  1. **动作头蒸馏**：教师 = UnifoLM-WLA-1.0（frozen VLM + DiT action head）；学生 = 缩窄 DiT（层数/通道/attention head 减少）+ 降 LoRA rank。损失 = flow-matching 速度场一致性 + 动作 L2 + 教师隐特征对齐。
  2. **结构化剪枝**：按 action-head 通道重要性（权重 ℓ2 × 激活均值）迭代剪 20–40%，每轮短微调恢复。
  3. **量化**：VLM 用 fp8/INT8，action head 保持 fp16 以防接触精度损失；可选 QAT。
  4. **单模型合规**：所有任务共享一个 trunk，仅用轻量任务嵌入/技能 token 条件化，不做多模型路由（A4）。
- **技术可行性**：中-高。教师权重与训练脚本官方可得（F11/F16），蒸馏是标准流程；难点是保留稀有技能的接触精度。
- **所需资源**：1×24GB 起步（LoRA 蒸馏）；剪枝+QAT 4–8 GPU 日；离线教师推理需 1 张卡。
- **落地步骤**：①教师 baseline p99/精度；②学生结构搜索（2–3 档宽度）；③蒸馏训练；④剪枝 + 短微调；⑤量化 + 健康度回归；⑥验收：p99<40ms、held-out 每任务 Δμ≥−1 分、救援带 Δμ>0。
- **风险**：蒸馏丢稀有技能（缓解：按任务族分层验收，退步族回退到教师；保留教师作 L0 oracle）；量化伤接触精度（缓解：action head 不量化；接触窗用高精度子网）；单模型边界（确认前不上计分通道）。

### I11 比赛策略：任务经济学 + ROI 背包 + 提交状态机（新）★★★★★
- **动机**：32 任务平均分下，资源错配是最大的隐性损失（P1/P11）；创新点越多，维护税与组合爆炸越重。
- **与现有方案差异**：别人按「创新点清单」平均用力或追单点 SOTA；本点把比赛显式建模为**带预算的期望分数组合优化**，并管理提交节奏。
- **技术方案**：
  1. **任务经济学表 E_i=(μ_i, σ_i², c_i, b_i)**：μ/σ 由 L0 代理 + 历史真机回填；c 用统一成本单位；b_i 由 p_i∈[0.2,0.6] 判定。
  2. **ROI 背包**：解定义 2 的 0/1 背包（含协同项），预算 B = GPU 时 + 人日 + 真机槽的加权和；每轮重解。
  3. **双模分配**：能力投入 → p≈0 的任务；可靠性/轻量化投入 → 救援带（定义 3）；p≈1 只做回归。
  4. **S/C 提交状态机**：安全基线 S 永远可提交；候选 C 过 PR4 + L2 才晋升；异常回滚。
  5. **反榜单过拟合**：限制公开榜单查询次数；用留出任务/留出种子做内部排名；不以单次榜单波动改策略。
- **技术可行性**：高（表格 + 脚本 + 小整数规划）。
- **所需资源**：1 人周建表与脚本；无额外 GPU。
- **落地步骤**：①32 任务 E_i 初始化（专家先验 + 已有结果）；②ROI 背包脚本；③首个决策 = I7 裁撤复核 + I2 扩容；④S/C 状态机接入提交脚本；⑤每轮复盘 ROI 预测误差。
- **风险**：ROI 估计噪声导致错配（缓解：bootstrap CI + 裁撤只在上界仍低时执行）；A1 若为加权平均则重排（缓解：把权重作为参数，公式不变）；榜单不公开时无法校准（缓解：以内部留出集为主）。

### I12 统一轻量护栏（新，合并 I3/I4）★★★★
- **动机**：I3（接触伺服）与 I4（干预门控）各自 <50ms 级，但两个独立状态机在 N 端口下的状态隔离与故障面是维护税（P11）；且二者都只降方差、不直接涨均值。
- **本轮变化**：合并为一个 **<5ms 单门**，共享一个 episode 状态机，按优先级串行：
  1. **硬边界**（永远执行，fail-safe）：关节/EE 界内、单步位移上限、NaN/Inf 拒绝。
  2. **动作健康**（fail-open）：平滑度（二阶差分）、统计正常性（与示教动作分布距离）。
  3. **干预判别**（I4 精简）：视觉手检测 + 本体残差 log-odds，连续 2 步迟滞；命中 → 停持/短 chunk。
  4. **接触 veto**（I3 精简）：仅在接触窗生效，只允许「延后闭合 / 夹爪开度 clamp」，不生成自由空间轨迹。
- **与现有方案差异**：不是三个模块相加，而是**一个门 + 四级优先级**；不确定时 fail-open（放行动作），只有硬边界 fail-safe（拒绝）。
- **技术可行性**：高。全部是规则 + 轻量检测，无新训练。
- **所需资源**：1 人周工程；<5ms/步。
- **落地步骤**：①把 I3/I4 规则迁移到单状态机；②优先级与 fail-open/fail-safe 语义单测；③N 端口状态隔离测试；④L0 验证不伤标称；⑤替换原 I3/I4。
- **风险**：单点故障（缓解：fail-open 默认 + 硬边界独立常开）；合并后难定位（缓解：每级独立日志与开关，可逐级降级）。

### 2.1 ROI 背包与救援带分配（I11）

```python
def allocate(tasks, actions, budget, synergy):
    # tasks[i] = (mu, var, cost_per_point, p_next)
    # actions[a] = (delta_mu, cost, task_ids, needs_L2)
    # 0/1 knapsack with pairwise synergy; n<=15 -> exact DP / ILP
    gain = {a: actions[a].delta_mu for a in actions}
    for a in actions:
        for b in actions:
            if a < b and (a, b) in synergy:
                gain[(a, b)] = synergy[(a, b)]
    # rescue-band: reliability actions get weight p*(1-p) per target task
    def rescue_weight(a):
        return sum(tasks[i].p_next * (1 - tasks[i].p_next)
                   for i in actions[a].task_ids)
    value = {a: gain[a] * (1 + RESCUE_LAMBDA * rescue_weight(a)) for a in actions}
    return knapsack_exact(value, {a: actions[a].cost for a in actions}, budget)

def should_kill(action, registry, roi_floor):
    lo, hi = registry.bootstrap_ci(action, n=1000)   # 95% CI of ROI
    return hi < roi_floor        # 只有上界仍低于阈值才裁撤，避免噪声误杀
```

def distill(teacher, student, data, L_max=0.040, lambda_feat=0.5):
    for obs, lang, a_teacher in data:            # a_teacher 由教师离线生成
        with torch.no_grad():

class SubmissionFSM:
