# 第 55 轮（承接第 54 轮 v16 GroundEdge-GenSim+++；灵感循环第 6 轮；本轮灵感：「UniBot-V1」×「用户需求分析」）

> 第 54 轮把技能组合推进到动作空间剖面与云边协同闭环，整条证书链已能证明“系统能做什么”。但它回答不了“用户要什么”。本轮把方向翻转：**以用户需求为第一性输入，建立 需求原子 → 能力证书 → 覆盖判定 → 缺口闭环 → 发布闸门 的双向闭环**，为 UniBot-V1 提供可审计的“需求—能力”对齐。核心矛盾：H22：自下而上的鲁棒性/动作证书是**能力包络**，自上而下的用户需求是 **KPI 诉求**，二者之间存在“证书 sound 但需求不满足”的语义鸿沟；H23：用户需求天然含歧义、冲突与漂移，若把需求当作确定性输入，证书会精确地回答一个错误的问题。

## 0. 直觉与动机

**灵感 1（需求不是一句话，是可测原子）**
直觉：用户说“UniBot 要更可靠”，这句话无法验收。把它拆成 `任务 × 上下文 × KPI × 阈值 × 优先级 × 歧义区间` 后，才能变成可判定命题：“在厨房湿滑地面、有人走动的上下文下，抓取玻璃杯的单次成功率 ≥ 0.95，优先级 must。” 关键不只是拆解，而是**保留歧义**——不同用户给出的阈值往往不一致，不能取平均冒充共识，而应记成区间 `U_r` 与出处。这样，需求分析从“需求文档”变成**带 provenance 的偏序集合**。

**灵感 2（证书给的是包络，不是结论）**
直觉：证书 `J=(ρ,A_cert,γ_ce,δ_a,evidence)` 只能推出 KPI 的上下界 `Env_J(r)=[lo,hi]`，不能直接告诉你“达标”。若阈值 `θ` 落在区间内部，就必须诚实地记为 **undetermined（undet）**，而不是“默认通过”。这条三值纪律是本轮最反直觉但最重要的设计：它把“证书 sound”与“需求 satisfied”之间的鸿沟显式暴露出来，而不是用二值 pass 掩盖。

**灵感 3（很多“能力不足”其实是“需求冲突”）**
直觉：两个利益相关者分别要求“更快响应”和“更高安全裕度”，可能在任何部署下都不可同时满足。若先埋头训练技能，等于用工程成本偿还一个逻辑上无解的需求。因此必须先做**需求冲突检测**：对同一任务/上下文，找出最小不可满足子集（MUS），把“能力问题”与“需求矛盾”分开，再决定是谈判还是研发。对 UniBot-V1 这类首个产品版本，这一步能显著减少无效迭代。

**灵感 4（缺口闭环：加能力是最后手段，不是第一手段）**
直觉：面对需求缺口，有五类闭环动作：`improve`（升级/新增技能）、`recompose`（复用第 54 轮技能组合图 `G_S` 扩展包络）、`constrain`（收窄运行上下文）、`renegotiate`（在利益相关者授权带内调整阈值）、`accept-risk`（签署风险接受）。V1 的目标不是“能力最强”，而是在预算内最大化**优先级加权覆盖**，即选择最便宜且可审计的闭环组合。

**灵感 5（需求会漂移，证书要增量重认证）**
直觉：UniBot-V1 发布后，需求版本持续演进。全量重跑测试与仿真不可持续，因此用**需求溯源超图**记录 `需求→任务→技能→证书→证据` 的推导，需求变更时只计算影响集、只重认证受影响且证据过期的证书。最后以**发布闸门 UBG**把硬需求覆盖、软需求覆盖、残留风险、证据新鲜度统一卡关，输出可签名的发布证书。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（用户需求原子）**
需求原子 `r = ⟨id, t, c, ψ, θ, δ, p, U, prov⟩`：
- `t ∈ T` 为任务描述；
- `c` 为运行上下文分布（`supp(c) ⊆ C`，刻画“在什么条件下”）；
- `ψ : (Deployment × C) → ℝ` 为 KPI 泛函（成功率、时延、安全裕度、能耗等，可多维）；
- `θ` 为验收阈值，`δ∈{≥,≤}` 为验收方向；
- `p ∈ {must, should, could}` 为优先级，满足偏序 `must ≻ should ≻ could`；
- `U = [θ_lo, θ_hi] ⊇ {θ}` 为**歧义区间**（不同利益相关者给出的阈值范围）；
- `prov` 为来源（利益相关者、原话、版本、时间戳）。
需求集合 `R = R_must ⊔ R_should ⊔ R_could`；`p=must` 称为硬需求。

**定义 122（证书蕴含包络与三值判定）**
给定证书 `J` 与需求原子 `r`，验证器导出 KPI 包络 `Env_J(r) = [lo, hi]`，并要求 soundness：
```
∀ D ⊨ J, ∀ c ∈ supp(c_r):  ψ(D, c) ∈ [lo, hi]
```
三值判定
```
ν_J(r) = pass  若 δ=≥ 且 lo ≥ θ_hi（或 δ=≤ 且 hi ≤ θ_lo）
       = fail  若 δ=≥ 且 hi < θ_lo（或 δ=≤ 且 lo > θ_hi）
       = undet 否则（阈值歧义区间与包络相交）
```
**关键**：`pass` 必须覆盖**最坏阈值** `θ_hi`，`fail` 必须覆盖**最宽松阈值** `θ_lo`，中间一律 `undet`。这三值判定是“证书→需求”唯一诚实的桥。

**定义 123（需求覆盖证书 RCC）**
需求覆盖证书 `RCC(R, J) = (ν, cov, Risk, fresh, W, sig)`：
- `ν : R → {pass, fail, undet}` 为三值判定；
- `cov(r) ∈ [0,1]` 为实测覆盖（在 `supp(c_r)` 上满足 `ψ` 的频率）；
- `Risk = Σ_{r: ν(r)≠pass} w(r)·(1 - cov(r)) + λ_e·Σ_{r: ν=undet} w(r)`，其中 `w(r)` 为优先级权重，`λ_e` 为认知不确定性罚项；
- `fresh = 1[age(evidence) ≤ ttl]` 对所有 must 路径成立；
- `W` 为逐需求见证集（测试 ID、仿真轨迹、现场日志）；
- `sig` 为利益相关者与 QA 的签名。
定义硬/软覆盖：
```
Cov_hard = min_{r∈R_must} cov(r)
Cov_soft = Σ_{r∈R_should∪R_could} w(r)·cov(r) / Σ w(r)
```

**定义 124（需求缺口与闭环动作）**
缺口集 `G = {r ∈ R : ν(r) ≠ pass}`。对每个缺口，闭环动作集
```
Ω(r) = { improve, recompose, constrain, renegotiate, accept-risk }
```
动作 `a` 有成本 `χ(a)`、对需求 `r` 的期望覆盖增益 `Δ(a,r)`、以及是否需签署。闭环规划为预算约束下的**优先级词典序最大覆盖**：
```
lex-max  ( Cov_hard, Σ_r w(r)·z_r )
s.t.      Σ_a χ(a)·x_a ≤ B,   z_r ≤ Σ_{a∈Ω(r)} Δ(a,r)·x_a,   z_r ≤ 1
          accept-risk 仅当 r ∈ R_should∪R_could 且签名齐全
```

**定义 125（需求溯源超图）**
需求溯源超图 `H_RT = (V, E)`：
- `V = R ∪ T ∪ S ∪ J ∪ Ev`（需求、任务、技能、证书、证据）；
- 超边 `e = (r, t, {S_i}, J, ev)` 表示“需求 r 经任务 t、由技能集 {S_i} 的证书 J 与证据 ev 支撑”。
**sound trace** 需满足：(i) 每条 must 需求存在到某个有效 `J` 的新鲜路径；(ii) 每个 `J` 至少被一条需求向上引用（无孤儿证书）；(iii) 跨版本不形成环。
需求变更 `ΔR` 的影响集 `I(ΔR) = {J : ∃ r∈ΔR, H_RT 中存在 r→J 路径}`。

**定义 126（UniBot-V1 发布闸门 UBG）**
发布状态 `Release(R, RCC, H_RT, ΔR) ∈ {ship, hold, reject}`，`ship` 当且仅当：
1. `Cov_hard = 1`（所有 must 需求 `pass`，或持有签名豁免且 `cov=1`）；
2. `Cov_soft ≥ κ`；
3. `Risk ≤ B`；
4. `H_RT` sound，且所有 must 路径证据 `fresh=1`；
5. 影响集 `I(ΔR)` 内证书均已重认证或豁免。
输出 `ReleaseCert = (RCC, H_RT hash, ΔR, impact, sig)`，可审计、可回溯。

## 2. 关键算法 伪代码

### IP-121 URA（User Requirement Atomization）

```python
def atomize(narratives, schema, stakeholders):
    atoms = []
    for n in narratives:
        cand = llm_extract(n, schema)          # t, c, psi, theta, delta, p
        for r in cand:
            r.U = ambiguity_interval(r, stakeholders)   # [min theta, max theta]
            r.prov = provenance(n, r.source)
            assert schema.validate(r)
            atoms.append(r)
    return resolve_duplicates_and_units(atoms)

def ambiguity_interval(r, stakeholders):
    vals = [s.theta for s in stakeholders if s.mentions(r.t)]
    return (min(vals), max(vals)) if vals else (r.theta, r.theta)
```

### IP-122 RCM（Requirement-Capability Matrix）

```python
def requirement_capability_matrix(R, Js, testbank, alpha=0.05):
    M = {}
    for r in R:
        for J in Js:
            lo, hi = certify_envelope(J, r, testbank, alpha)  # sound interval
            if r.delta == '>=':
                v = 'pass' if lo >= r.U[1] else ('fail' if hi < r.U[0] else 'undet')
            else:
                v = 'pass' if hi <= r.U[0] else ('fail' if lo > r.U[1] else 'undet')
            M[(r.id, J.id)] = (v, (lo, hi), witness(J, r))
    return M

def detect_conflicts(R, M):
    groups = group_by_task_context(R)
    conflicts = []
    for g in groups:
        if not any(all(M[(r.id, J.id)][0] != 'fail' for r in g) for J in certs):
            conflicts.append(quickxplain(g, M))   # minimal unsatisfiable subset
    return conflicts
```

### IP-123 RCC（Requirement Coverage Certificate）

```python
def coverage_certificate(R, M, ttl):
    nu, cov, W = {}, {}, {}
    for r in R:
        best = select_best(M, r)                  # prefer pass > undet > fail
        nu[r.id], W[r.id] = best.verdict, best.witness
        cov[r.id] = measure_coverage(best, r)     # over supp(c_r)
    risk = sum(w(r) * (1 - cov[r.id]) for r in R if nu[r.id] != 'pass') \
         + lambda_e * sum(w(r) for r in R if nu[r.id] == 'undet')
    fresh = all(age(W[r.id].evidence) <= ttl for r in R if r.priority == 'must')
    return RCC(nu, cov, risk, fresh, W, collect_signatures(R))
```

### IP-124 RGC（Requirement Gap Closure）

```python
def close_gaps(R, G, Omega, B):
    # 先用公式 (2) 强制 hard 覆盖，再对软需求做 (1-1/e) 贪心最大覆盖
    plan, budget, covered = [], B, set()
    for r in sorted(G, key=lambda x: x.priority == 'must', reverse=True):
        if r.priority == 'must':
            a = argmin_cost(Omega[r], need=r)     # 硬需求必须闭合或显式失败
            if a is None or chi(a) > budget: return ('hold', 'hard_unclosable', r)
            plan.append(a); budget -= chi(a); covered.add(r.id)
    while budget > 0:
        a = argmax_a sum(w(r) * Delta(a, r) for r in Omega_inv(a) if r.id not in covered) / chi(a)
        if a is None or chi(a) > budget: break
        plan.append(a); budget -= chi(a)
        covered |= {r.id for r in Omega_inv(a)}       # marginal gain accounting
    return ('ok', plan, covered_report(covered, R))
```

### IP-125 RTH（Requirement Traceability Hypergraph）

```python
def build_trace(R, M, evidence, certs):
    H = Hypergraph()
    for r in R:
        for J in candidate_certs(r, certs):
            if M[(r.id, J.id)][0] != 'fail':
                H.add_hyperedge((r, task_of(r), skills_of(J), J, evidence[J.id]))
    assert no_orphan_certs(H, certs)
    assert all_must_reachable(H, R)
    return H

def impact_set(H, delta_R):
    reached, frontier = set(), set(delta_R)
    while frontier:
        r = frontier.pop()
        for J in H.successors_of_requirement(r):
            if J not in reached:
                reached.add(J); frontier |= H.requirements_of_cert(J)
    return reached
```

### IP-126 UBG（UniBot-V1 Release Gate）

```python
def release_gate(R, RCC, H, delta_R, kappa, B, ttl, waivers):
    must = [r for r in R if r.priority == 'must']
    if any(RCC.nu[r.id] != 'pass' and r.id not in waivers for r in must):
        return ('reject', 'hard_uncovered')
    if RCC.cov_soft < kappa or RCC.risk > B:
        return ('hold', 'soft_or_risk_budget')
    if not trace_sound(H) or stale_evidence(H, ttl):
        return ('hold', 'trace_or_freshness')
    impacted = impact_set(H, delta_R)
    redo = [J for J in impacted if not reusable(J, delta_R)]
    if redo:
        return ('hold', 're_certify', redo)       # 增量重认证，不全量重跑
    return ('ship', ReleaseCert(RCC, hash(H), delta_R, impacted, signatures()))
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| URA | O(|R|·|stakeholders|) | O(|R|) | schema 完备、歧义区间不塌缩 |
| RCM | O(|R|·|J|·|testbank|) | O(|R|·|J|) | 包络 sound、三值边界保守 |
| RCC | O(|R|·|C|) | O(|R|) | 见证可复现、证据新鲜 |
| RGC | O(|R|·|Ω|·log|R|) | O(|R|+|Ω|) | hard 优先、预算闭合 |
| RTH | O(|R|·|J|·|ev|) | O(|V|+|E|) | 无孤儿证书、must 可达 |
| UBG | O(|ΔR|·deg(H)) | O(|I(ΔR)|) | 影响集最小充分、证据 ttl |

**正确性定理（Requirement-Coverage Soundness for UniBot-V1）**
假设 (A22)–(A28) 承接第 54 轮；**(A29)** 每个需求原子的 `ψ_r` 可由结构化测试/仿真评估，且测试分布覆盖 `supp(c_r)`；**(A30)** 证书包络 `Env_J(r)` 相对真实系统 sound（由第 53–54 轮 ρ/A_cert 证书保证）；**(A31)** 证据在 `ttl` 内且可复现；**(A32)** 需求原子化经至少一名利益相关者回签，歧义区间 `U_r` 非退化。则对硬需求：
```
P(∀ r∈R_must : sat(r) | RCC=pass) ≥ 1 - β_cert - β_test - β_form
```
对软需求：
```
E[Cov_soft] ≥ Σ w(r)·cov(r)/Σw(r) - β_cert - β_test ，且 Risk ≤ B 给出最坏情形上界
```
其中 `β_cert` 为包络 soundness 失败率，`β_test` 为测试分布偏差，`β_form` 为需求形式化与真实用户意图的偏差。
**关键**：前三项可由证书与实验控制，**唯独 `β_form` 不可由系统内部证明，只能靠回签与现场监测降低**——这正是下一节风险所在。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 需求形式化偏离真实用户意图（GIGO） | 高 | 利益相关者回签 + 原话 provenance + 现场验收对照 |
| 三值判定被滥用为“默认通过” | 高 | pass 必须有见证、undet 计入风险、红队反例审计 |
| 上下文分布漂移导致包络失效 | 高 | 现场遥测 + 分布检验 + 证据 ttl 强制过期 |
| 需求膨胀 / 优先级博弈 | 中 | 优先级治理、预算封顶、must 名额约束 |
| 溯源超图规模爆炸 | 中 | 版本化哈希、按影响集增量构建、边剪枝 |
| 冲突检测漏报导致无效研发 | 中 | MUS 快速算法 + 人工复核 + 冲突台账 |

## 6. 本轮最大风险

**一句话**：需求覆盖证书把 UniBot-V1 的“能力”与“用户诉求”用三值判定和发布闸门硬接起来，但整条链的 soundness 最终被 `β_form`（需求形式化与真实用户意图的偏差）这一不可内部证明的量所支配；一旦原子化把用户真正的需求拆错、或歧义区间被强行塌缩成单点阈值，再 sound 的证书也只会精确地回答一个错误的问题，故必须以 **利益相关者回签 + 原话溯源 + 现场需求漂移监测 + 诚实的 undet 记账** 四重护栏，把“发布通过”限定为“在已形式化的需求集合上通过”，绝不宣称“满足用户”。

# 第 55 轮产物 · 创新点清单 v32：UniBot-ReqCert（URA×RCM×RCC×RGC×RTH×UBG）

> 承接第 54 轮产物 v31。本轮把研究从“能力自证”翻转为“需求对齐”，在 v16 GroundEdge-GenSim+++ 之上叠加 **需求层**：
> - **URA（User Requirement Atomization）**：把用户叙事拆成带歧义区间与 provenance 的可测需求原子；
> - **RCM（Requirement-Capability Matrix）**：需求 × 证书的三值覆盖矩阵 + 需求冲突（MUS）检测；
> - **RCC（Requirement Coverage Certificate）**：硬/软覆盖、残留风险、证据新鲜度的可签名证书；
> - **RGC（Requirement Gap Closure）**：缺口 → 升级/重组/收窄/重谈/接受 的预算内闭环规划；
> - **RTH（Requirement Traceability Hypergraph）**：需求→任务→技能→证书→证据的溯源与影响分析；
> - **UBG（UniBot-V1 Release Gate）**：可审计的发布闸门 + 需求漂移增量重认证。
>
> IP 编号：IP-121~IP-126（共 6 个新增），升级 IP-115/116/118 以接受需求侧输入。

```python
def atomize(narratives, schema, stakeholders):
    atoms = []
    for n in narratives:
        for r in llm_extract(n, schema):          # t,c,psi,theta,delta,p
            r.U = ambiguity_interval(r, stakeholders)
            r.prov = provenance(n, r.source)
            assert schema.validate(r)             # 单位、量纲、方向必须显式
            atoms.append(r)
    return resolve_duplicates_and_units(atoms)

def ambiguity_interval(r, stakeholders):
    vals = [s.theta for s in stakeholders if s.mentions(r.t)]
    return (min(vals), max(vals)) if vals else (r.theta, r.theta)
```

### IP-122 RCM

```python
def requirement_capability_matrix(R, Js, testbank, alpha=0.05):
    M = {}
    for r in R:
        for J in Js:
            lo, hi = certify_envelope(J, r, testbank, alpha)   # sound interval
            if r.delta == '>=':
                v = 'pass' if lo >= r.U[1] else ('fail' if hi < r.U[0] else 'undet')
            else:
                v = 'pass' if hi <= r.U[0] else ('fail' if lo > r.U[1] else 'undet')
            M[(r.id, J.id)] = (v, (lo, hi), witness(J, r))
    return M

def detect_conflicts(R, M, certs):
    conflicts = []
    for g in group_by_task_context(R):
        if not any(all(M[(r.id, J.id)][0] != 'fail' for r in g) for J in certs):
            conflicts.append(quickxplain(g, M))    # minimal unsatisfiable subset
    return conflicts
```

### IP-123 RCC

```python
def coverage_certificate(R, M, ttl, lambda_e=0.5):
    nu, cov, W = {}, {}, {}
    for r in R:
        best = select_best(M, r)                   # pass > undet > fail
        nu[r.id], W[r.id] = best.verdict, best.witness
        cov[r.id] = measure_coverage(best, r)      # over supp(c_r)
    risk = sum(w(r)*(1-cov[r.id]) for r in R if nu[r.id] != 'pass') \
         + lambda_e * sum(w(r) for r in R if nu[r.id] == 'undet')
    fresh = all(age(W[r.id].evidence) <= ttl for r in R if r.priority == 'must')
    return RCC(nu, cov, risk, fresh, W, collect_signatures(R))
```

### IP-124 RGC

```python
def close_gaps(R, G, Omega, B):
    plan, budget, covered = [], B, set()
    # 1) 硬需求优先：必须闭合，否则 hold 并报告，不允许静默降级
    for r in [x for x in G if x.priority == 'must']:
        a = argmin_cost(Omega[r], need=r)
        if a is None or chi(a) > budget:
            return ('hold', 'hard_unclosable', r)
        plan.append(a); budget -= chi(a); covered.add(r.id)
    # 2) 软需求：贪心最大覆盖，(1-1/e) 近似
    while budget > 0:
        a = argmax_a sum(w(r)*Delta(a,r) for r in Omega_inv(a) if r.id not in covered) / chi(a)
        if a is None or chi(a) > budget: break
        plan.append(a); budget -= chi(a)
        covered |= {r.id for r in Omega_inv(a)}
    return ('ok', plan, covered_report(covered, R))
```

### IP-125 RTH

```python
def build_trace(R, M, evidence, certs):
    H = Hypergraph()
    for r in R:
        for J in candidate_certs(r, certs):
            if M[(r.id, J.id)][0] != 'fail':
                H.add_hyperedge((r, task_of(r), skills_of(J), J, evidence[J.id]))
    assert no_orphan_certs(H, certs)               # 每个证书都被需求引用
    assert all_must_reachable(H, R)                # must 需求均可溯源
    return H

def impact_set(H, delta_R):
    reached, frontier = set(), set(delta_R)
    while frontier:
        r = frontier.pop()
        for J in H.successors_of_requirement(r):
            if J not in reached:
                reached.add(J); frontier |= H.requirements_of_cert(J)
    return reached
```

### IP-126 UBG

```python
def release_gate(R, RCC, H, delta_R, kappa, B, ttl, waivers):
    must = [r for r in R if r.priority == 'must']
    if any(RCC.nu[r.id] != 'pass' and r.id not in waivers for r in must):
        return ('reject', 'hard_uncovered')
    if RCC.cov_soft < kappa or RCC.risk > B:
        return ('hold', 'soft_or_risk_budget')
    if not trace_sound(H) or stale_evidence(H, ttl):
        return ('hold', 'trace_or_freshness')
    impacted = impact_set(H, delta_R)
    redo = [J for J in impacted if not reusable(J, delta_R)]
    if redo:
        return ('hold', 're_certify', redo)        # 只重认证影响集，不全量重跑
    return ('ship', ReleaseCert(RCC, hash(H), delta_R, impacted, signatures()))

def reusable(J, delta_R):
    # 证据仍新鲜、技能与上下文未变、且 delta_R 未触及该证书的 must 路径
    return J.evidence.fresh and J.skill_hash == current_hash(J.skill) \
       and not any(r in J.must_requirements for r in delta_R)
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| URA | O(|R|·|stakeholders|) | O(|R|) | schema 完备、歧义区间不塌缩 |
| RCM | O(|R|·|J|·|testbank|) | O(|R|·|J|) | 包络 sound、三值边界保守 |
| RCC | O(|R|·|C|) | O(|R|) | 见证可复现、must 证据新鲜 |
| RGC | O(|R|·|Ω|·log|R|) | O(|R|+|Ω|) | hard 优先、预算闭合、(1-1/e) 近似 |
| RTH | O(|R|·|J|·|ev|) | O(|V|+|E|) | 无孤儿证书、must 可达、影响集最小充分 |
| UBG | O(|ΔR|·deg(H)) | O(|I(ΔR)|) | 影响集重认证、签名可审计 |

**正确性定理（Requirement-Coverage Soundness for UniBot-V1）**
假设第 54 轮 (A22)–(A28) 成立；**(A29)** 需求 KPI 可由结构化测试评估且测试分布覆盖 `supp(c_r)`；**(A30)** 证书包络 sound；**(A31)** 证据在 ttl 内且可复现；**(A32)** 需求原子化经利益相关者回签、歧义区间非退化。则
```
P(∀ r∈R_must: sat(r) | Release=ship) ≥ 1 - β_cert - β_test - β_form - P(β_drift)
E[Cov_soft] ≥ Σ w(r)cov(r)/Σw(r) - β_cert - β_test
```
其中 `β_cert/β_test` 由证书与实验控制，`β_form` 为需求形式化偏差、`β_drift` 为发布后需求漂移，二者**不可由系统内部证明**。

**一个最小算例（玻璃杯抓取）**：
需求 `r`：厨房湿滑 + 有人走动，抓取成功率 `ψ≥θ`，`θ∈[0.93,0.97]`（两位利益相关者不一致），`p=must`。
第 54 轮证书给出 `Env_J(r)=[0.95,0.99]`。因 `lo=0.95 < θ_hi=0.97`，判定为 **undet**（不是 pass）。
RCM 记录该区间的证据缺口；RGC 选择 `constrain`（限定地面湿度上限）使 `Env` 收窄为 `[0.97,0.99]`，成本低于 `improve`；重算后 `lo≥θ_hi`，转 pass，UBG 才允许 ship。这个算例说明：**三值判定迫使系统承认“差一点就是没到”**，而不是靠均值粉饰。

## 5. 本轮最大风险

**一句话**：需求覆盖证书把 UniBot-V1 的“能力”与“用户诉求”用三值判定和发布闸门硬接起来，但整条链的 soundness 最终被 `β_form`（需求形式化与真实用户意图的偏差）这一不可内部证明的量所支配；一旦原子化把用户真正的需求拆错、或歧义区间被强行塌缩成单点阈值，再 sound 的证书也只会精确地回答一个错误的问题，故必须以 **利益相关者回签 + 原话溯源 + 现场需求漂移监测 + 诚实的 undet 记账** 四重护栏，把“发布通过”限定为“在已形式化的需求集合上通过”，绝不宣称“满足用户”。
