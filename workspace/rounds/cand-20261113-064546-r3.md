# 第 3 轮迭代（灵感循环 v3：「事件相机」×「用户画像」）—— 从"事后检测撤回"到"事件触发的人扰画像预判-恢复"

> 承接第 2 轮 UIP-01′~15。第 2 轮回答的是"进度被反向撤回后，如何发现并重做"；本轮两个词把它再推两步：**事件相机**回答"用什么样的廉价信号，在成百上千帧里只盯住'变化'"；**用户画像**回答"变化是谁造成的、下一步会撤回什么"。本轮最重要的口径修正先说死：**评测在远端真机进行、选手不能加装传感器**，所以"事件相机"在本方案里严格降维为**从接口已有 RGB 帧流构造的"软件事件前端"（SEF）**，绝不冒充硬件事件相机；"用户画像"也从营销语义重定义为**人扰干预的标记点过程模型（HIP）**。两者合成的旗舰是 **UIP-01″ EIPAR**：事件触发、画像条件化、分数加权的稀疏验证-预判-恢复。

## 1. 上轮清单诊断（升级 / 合并 / 修剪）

- **升级为旗舰 UIP-01″（EIPAR）**：第 2 轮 UIP-01′ 的 `regressed` 状态机仍然正确，但它假设"每 k 步都调用验证器"。本轮改为**事件触发 + 画像排序 + 分数加权**：只在有意义的变化发生时、只对最可能被撤回的子目标调用验证器。
- **并入**：UIP-09′（DCR-R）不再单列，它就是 UIP-01″ 的"检测-重做"腿；UIP-12（DRF）升级为 **UIP-18 PEDF**，增加事件签名与曝光/噪声增强；UIP-15（CSG）升级为 **UIP-19 E-CSG**，因为事件触发会让请求流量呈突发状，必须用令牌桶约束。
- **保留并各司其职**：UIP-02′（32 任务计分表，提供"分数加权"的分值）、UIP-11（GSO，离线裁判）、UIP-13（ACS，提供块长 k 的旋钮）、UIP-14（MSGR，提供技能图与**任务相关区域掩码**）、UIP-08′（多端口延迟工程）、UIP-05（语言→可供性分解）。
- **修剪**：删去第 2 轮已改号的 UIP-07′ 行；UIP-04/UIP-10 维持封存；UIP-03 已并入 UIP-14。
- **为什么不是推翻重来**：`done/ongoing/fail/regressed` 状态机、计分步顺序、Gazebo 造数据三条主线全部保留；本轮只改**两个问题**——"何时调用验证器"与"先验证谁"。

## 2. 两个灵感词：先直觉，再严谨定义

### 2.1 事件相机

**直觉**：事件相机像一层"只记录变化的视网膜"——静止场景几乎不产生数据，人一伸手、物体一被拉动，事件流立刻在对应位置"亮"起来；它常被描述为微秒级、高动态范围、不怕运动模糊。

**严谨定义（本赛题版）**：设第 $t$ 帧对数亮度为 $L_t(x)=\log I_t(x)$，参考帧为 $R_t(x)$，阈值 $\theta>0$。**软件事件前端 SEF** 输出
$$
e_t(x)=\begin{cases}\operatorname{sign}(L_t(x)-R_t(x)), & |L_t(x)-R_t(x)|\ge\theta\\ 0, & \text{otherwise}\end{cases},
\qquad
R_{t+1}(x)=\begin{cases}L_t(x), & e_t(x)\ne 0\\ (1-\lambda)R_t(x)+\lambda L_t(x), & e_t(x)=0\end{cases}
$$
再按任务相关区域（由 UIP-14 的技能图/物体掩码给出）聚合为事件能量 $E_t(c)=\sum_{x\in c}|e_t(x)|$。

**必须承认的三条硬限制**：
1. **不能超过帧率**：SEF 的事件时间分辨率 = 输入帧间隔，不是微秒；它不提供 HDR，也无法恢复已被 JPEG 压掉的高光/暗部。
2. **不能中断已下发的动作块**：评测端整块执行后才再次调用 `get_action`，所以"事件触发"只能影响**下一块**的长度与内容；实时收益必须通过 UIP-13 的块长实现。
3. **自运动会污染事件流**：机器人自己的手臂是画面里最大的运动源。必须先做**自运动扣除**（用已知关节角/上一动作投影出末端掩码，或用 head/wrist 双视角一致性），否则人扰信号会被自运动淹没。

一句话：**SEF 不是更快的眼睛，而是更省钱的注意力分配器。**

### 2.2 用户画像

**直觉**：先摸清"这个人"的习惯——总在你刚完成一步时出手、总从右边伸手、总爱把刚拉上的拉链重新拉开。摸清之后，就能提前半拍把验证算力挪到最可能被撤回的那一步上。

**严谨定义（本赛题版）**：这里的"用户"不是终端消费者，而是 `human_*` 的**干预者**。把人扰建模为任务条件的**标记点过程** $\{(t_i,m_i)\}$，标记 $m_i=(g_i,o_i,\rho_i,d_i)$：受影响子目标、物体、逆操作（unzip/open/unscrew/remove/unstack/displace）、持续时长。画像分两层：
- **全局风格** $\theta$：伸手方向、速度、完成里程碑后的干预延迟、偏好逆操作、左右手——可跨任务迁移（若同一干预者）。
- **任务模式** $\Pi_\tau=\{(\pi_{g,o,\rho})\}$：从 `info.json` 的 `human_*` 文本抽出的候选 schema 及先验权重。

在线用贝叶斯/狄利克雷计数更新；输出不是"结论"，而是**给验证器的候选子目标排序**与**预测干预窗口** $W_g$。铁律：**画像只负责"提案"，验证器负责"定罪"**；画像单独不得触发重做。

## 3. 瓶颈假设（v3，替换第 2 轮 H1）

- **H1（注意力预算，最高杠杆）**：真正的瓶颈不是"能否检测撤回"，而是"能否在延迟/算力预算内持续盯住所有可被撤回的子目标"。全域定期验证太贵；**事件触发的稀疏验证**才可能同时保住召回与延迟。
- **H2（人扰有结构）**：干预多发生在某子目标刚完成后的短窗口，且逆操作与物体绑定。文本先验可把候选从 $G$ 个压到 2 个；若成立，验证调用量可降一个量级。
- **H3（自运动污染）**：不扣除机器人自运动，SEF 的假阳性会淹没真信号；双视角一致性+末端投影是必需项，不是可选优化。
- **H4（块长耦合）**：事件不能中断已下发块。收益只能是"事件活动度高 → 下一块更短 → 更快重观测"；不与 ACS 联动则收益≈0。
- **H5（画像循环性）**：用自己写的 Gazebo 脚本训出的画像，很可能只是在"预测自己"。画像只能作先验，必须用真机/半真机锚点校准，否则是仿真自我欺骗。
- **H6（可信度突发）**：事件触发会制造突发重观测，抬高延迟抖动；必须令牌桶 + 最大重做次数，否则可信度判罚可能吃掉收益。

## 4. 候选与合并 → v3 清单（详见产物区）

围绕两个词发散 8 个草案，合并去重后得到：**UIP-01″（旗舰）+ UIP-16 SEF + UIP-17 HIP + UIP-18 PEDF + UIP-19 E-CSG**，并保留 UIP-02′/05/08′/11/13/14。被**主动放弃**的一个分支：把"用户画像"理解成"终端用户偏好个性化"——本赛题任务与物体固定，个性化不产生分数，故不采用。

- **UIP-16 SEF**：软件事件前端；帧差/对数亮度变化 + 自运动扣除 + 区域聚合。
- **UIP-17 HIP**：人扰画像；全局风格 + 任务 schema + 在线贝叶斯更新。
- **UIP-01″ EIPAR**：用 SEF 触发、HIP 排序、按"风险×分值/成本"选验证目标，并用预测窗口提前收缩块长。
- **UIP-18 PEDF**：用 Gazebo DRF 脚本 + v2e/ESIM 造"反向撤回 + 事件签名"数据，训练同骨干的事件小头。
- **UIP-19 E-CSG**：给事件触发重观测加令牌桶、重做上限与动作平滑。

## 5. 本轮最大风险与押注

**一句话最大风险**：把从自己脚本里学来的"人扰画像"当成真实对手模型——于是 SEF+画像在仿真里越跑越准，到真机上却连"是谁在动、动了什么、该重做哪一步"都分不清。

**→ 本轮押注：UIP-16 SEF × UIP-17 HIP × UIP-01″ EIPAR 的"事件触发稀疏验证"**——它把第 2 轮"每 k 步全域验证"的算力/延迟瓶颈，换成"只在外部运动出现时、只验最可能被撤回且分值最高的子目标"，且完全落在选手 API 权限与离线算力之内。

## 1. 旗舰深潜：UIP-01″ · EIPAR

**全称**：Event-triggered, Interferer-Profiled Anticipatory Recovery。

### 1.1 决策形式化（为什么"验谁"比"怎么验"更重要）

在每次重观测边界 $t$，设候选子目标集合为 $G_\tau=\{1,\dots,G\}$。对每个子目标 $g$：
- $p_g(t)$：当前/即将被撤回的概率（由 UIP-17 给出，并由 UIP-16 的事件能量门控）；
- $s_g$：该计分步的分值（来自 UIP-02′ 的 32 任务表，末步通常 40/50）；
- $r_g$：检测到撤回后**恢复成功**的条件概率（由技能图与历史统计估计）；
- $c_g$：调用验证器的时间成本。

定义**期望保住分数** $V_g(t)=p_g(t)\cdot s_g\cdot r_g$。验证预算为 $B$ 时，选择监控集合 $S\subseteq G_\tau$ 求解
$$
\max_{S}\ \sum_{g\in S} V_g(t)\quad \text{s.t.}\quad \sum_{g\in S} c_g\le B,
$$
用 $V_g/c_g$ 贪心即可。**这解释了为什么不能对 32 个任务一视同仁地高频验证**：末步 40–50 分的子目标值得盯，前置 20–30 分的子目标只在画像/事件提示时才盯。

事件门控：
$$
p_g(t)=p_g^{\text{profile}}(t)\cdot \sigma\!\big(\alpha\,(a_g(t)-a_0)\big),
$$
其中 $a_g(t)$ 是子目标 $g$ 相关区域内**扣除自运动后**的事件能量，$\sigma$ 为 sigmoid。**静默时不验证**（省算力/延迟），**有外部运动时不只验证，还收缩块长**。

### 1.2 预判（Anticipatory）而非只事后检测

UIP-17 给出每个高风险子目标完成后的预测干预窗口 $W_g=[\hat\mu_g-\delta,\hat\mu_g+\delta]$。在 $W_g$ 内：
1. 把 $g$ 的事件阈值下调（更敏感）；
2. 把下一块长度 $k$ 调小（提高重观测频率）；
3. 预生成"逆操作恢复块"（例如对 T19 预生成"重新拉合"、对 T27 预生成"重新叠碗"），事件确认后立即返回，省掉一轮推理。

### 1.3 恢复（Recovery）不是通用重试

撤回有**类型**：拉开、翻开、拧回、拿走、挪底座、放回起点。恢复应调用对应技能头的**逆操作**，并以"进度账本"中最后有效的几何谓词为目标，而不是从当前步盲目重跑。进度账本 `ledger[g]` 只在该子目标的验证谓词通过时置真；检测到 `regressed` 时只作废受影响的 $g$ 及其后继，前置有效步骤的分数被锁住（这直接对应第 2 轮"步骤分安全网"）。

### 1.4 主循环伪代码

```python
class EIPAR:
    def __init__(self, base, verifier, sef, profile, skillgraph,
                 K_MIN=2, K_MAX=16, theta_evt=0.15, conf_thr=0.7,
                 redo_cap=2, budget_ms=200):
        self.base, self.verifier, self.sef = base, verifier, sef
        self.profile, self.skillgraph = profile, skillgraph
        self.K_MIN, self.K_MAX, self.theta_evt = K_MIN, K_MAX, theta_evt
        self.conf_thr, self.redo_cap, self.budget_ms = conf_thr, redo_cap, budget_ms
        self.buf, self.prev_frame, self.last_action = [], None, None

    def reset(self, task):
        self.base.reset()
        self.task, self.g, self.redo = task, 0, 0
        self.ledger = {}
        self.buf, self.prev_frame, self.last_action = [], None, None
        self.profile.begin_episode(task)      # 跨 episode 持久性见 §9 未决项

    def get_action(self, obs):
        E = self.sef.events(obs.frames, self.prev_frame)          # 栈内帧 + 环形缓冲
        E = self.sef.cancel_ego(E, obs.proprio, self.last_action)  # H3：自运动扣除
        self.prev_frame = obs.frames[-1]

        cand = self.profile.topk(self.task, self.g, k=2)           # UIP-17 提案
        if self._should_verify(E, cand):                           # UIP-16 触发
            for g in cand:
                st, conf = self.verifier(obs, self.lang, self.skillgraph.knot(g))
                if conf < self.conf_thr:
                    continue
                if st == "regressed" and self.redo < self.redo_cap:
                    self.ledger.pop(g, None)                       # 只作废该步
                    self.g, self.redo = g, self.redo + 1
                    self.profile.observe(self.task, g,
                        self.sef.infer_mark(E, self.skillgraph.region(g)))
                    self.buf = []                                  # 丢弃旧块，立即重做
                    break
                if g == self.g and st == "done":
                    self.ledger[g] = True
                    self.g, self.redo = self.g + 1, 0

        k = self._chunk_len(E, self.profile.risk(self.g))          # UIP-13 联动
        if not self.buf:
            self.buf = list(self.base.get_action(obs, k))[:k]
        self.last_action = self.buf[0]
        return self.buf.pop(0)

    def _should_verify(self, E, cand):
        if self._periodic_fallback():                              # 防"静默撤回"
            return True
        if any(self.sef.activity(E, self.skillgraph.region(g)) > self.theta_evt
               for g in cand):
            return True
        return self.profile.in_window(self.task, self.g)

    def _chunk_len(self, E, risk_g):
        a = min(1.0, self.sef.activity(E, self.skillgraph.region(self.g)) / self.theta_evt)
        return int(round(self.K_MAX - (self.K_MAX - self.K_MIN) * max(a, risk_g)))
```

**关键实现约束**：`k` 每次可 ≤ metadata 声明的 `action_chunk_size`；返回块形状仍须 `(T_a, ...)` 且索引 0 先执行，否则触碰接口红线。

## 2. UIP-16 · SEF（Software Event Frontend）

### 2.1 产生事件

- **输入**：接口给的图像栈（由 `obs_delta_indices` 决定几帧；建议 2–3 帧，别为事件无限堆栈——每帧都是一张 JPEG）。
- **无栈时**：维护跨 `get_action` 的环形缓冲，用上一帧与当前帧做差分；时间分辨率退化为"调用间隔"，仍可检测慢速撤回。
- **对数亮度**：$L=\log(I+\epsilon)$，对光照变化比原始像素鲁棒；阈值 $\theta$ 可按相机/曝光自适应。
- **泄漏参考帧**：只更新触发像素，模拟 DVS 的"变化即重置参考"，抑制缓慢漂移的持续触发。

```python
def events(frames, prev=None, theta=0.15, leak=0.3):
    L = [log(f + 1e-3) for f in frames]
    if prev is not None:
        L = [prev] + L
    R, E = L[0].clone(), []
    for t in range(1, len(L)):
        d = L[t] - R
        e = where(abs(d) >= theta, sign(d), 0)
        E.append(e)
        R = where(e != 0, L[t], (1 - leak) * R + leak * L[t])
    return E            # 每帧一个稀疏 ON/OFF 图
```

### 2.2 自运动扣除（没有这一步，SEF 不可用）

机器人自己的手臂/夹爪是画面最大运动源。三层扣除，按成本从低到高：
1. **末端投影掩码**：用已知关节角与上一动作做正运动学，投影出末端执行器在相机中的预测区域，扣掉该区域的能量。
2. **双视角一致性**：head 与 wrist 同时在同一物体区域出现变化，才判为外部运动；只有 head 变化而 wrist 无变化，更可能是机器人自身或背景。
3. **动作预测残差**：用"上一动作预期造成的像素变化"作为基线，只保留残差事件。

```python
def cancel_ego(E, proprio, last_action):
    mask = project_end_effector(proprio, last_action)   # 预测自运动区域
    E = E * (1 - mask)
    return cross_view_consistency(E)                    # head/wrist 同区域才保留
```

### 2.3 输出给谁

- 给 **UIP-01″**：`activity(region)`、`infer_mark`（变化最集中的区域→物体/逆操作候选）。
- 给 **UIP-13**：归一化活动度 $a_t$ → 下一块长度 $k$。
- 给 **UIP-19**：事件突发强度 → 是否消耗令牌。

## 3. UIP-17 · HIP（Human Interferer Profile）

### 3.1 两层画像

| 层 | 内容 | 来源 | 生命周期 |
|---|---|---|---|
| 全局风格 $\theta$ | 伸手方向、速度、里程碑后延迟、偏好逆操作 | 在线事件积累 + 跨任务统计 | 尽量跨 episode（合规待确认） |
| 任务 schema $\Pi_\tau$ | 可能被撤回的子目标、物体、逆操作、时机 | `info.json.generalization.human_*` 文本 | 静态先验 |

**更新规则（简单、可解释、无需额外模型）**：对每个任务维护计数 $n_{\tau,g,\rho}$；观察到一次 `regressed` 且标记为 $(g,\rho)$ 时 $n_{\tau,g,\rho}\leftarrow n_{\tau,g,\rho}+1$，后验权重
$$
\pi_{\tau,g,\rho}=\frac{n_{\tau,g,\rho}+\alpha_{\tau,g,\rho}}{\sum_{g',\rho'}(n_{\tau,g',\rho'}+\alpha_{\tau,g',\rho'})},
$$
其中 $\alpha$ 由文本先验给出（例如 T19 的"拉开"先验高）。全局风格用同一套计数但跨任务汇总。

## 4. UIP-18 · PEDF（Pseudo-Event Disturbance Factory）

### 4.1 造什么

在 v2 的 UIP-12 基础上增加两类数据：
1. **反向撤回三元组**：`(干扰前 → 撤回 → 恢复)`，脚本化机械手按 `human_*` 文本执行（拧回、翻开、拉开、拿走、挪底座、放回起点），随机化**时机、速度、轨迹、手别**。
2. **事件签名与退化增强**：用 v2e 从公开 RGB/Gazebo 帧生成带阈值失配、噪声、有限带宽的事件流，用于**阈值标定**；用 v2e 对帧做低光/曝光/噪声增强，提升 SEF 在退化图像上的稳定性。

### 4.2 训练/推理一致性（最容易踩的坑）

- **训练 SEF 检测器时，输入必须是"与推理同款 SEF 产生的伪事件"**，而不是 v2e 的原始高时间分辨率事件；否则训练/推理输入分布不一致，线上必掉。
- v2e/ESIM 的事件只作**辅助分支**（同骨干的轻量事件头）或**阈值/数据增强的标定器**，不作为线上唯一输入。
- 事件头必须与主骨干共享参数（或从主骨干蒸馏），避免"第二个模型"的合规风险；最保守版本可完全不用学习头，只用阈值+区域规则。

### 4.3 风险

仿真里的"人手"是我们自己写的，**形态与时机都可能与真人不同**。PEDF 只应被当作"覆盖极端情况"的数据源，绝不能据此宣称真机有效；必须用真机干预片段做锚点（E210）。

## 5. UIP-19 · E-CSG（Event-triggered Credibility-Safe Governor）

事件触发会让重观测请求呈**突发状**：一段时间不验证，事件一来连续调用。这会抬高延迟均值/方差，直接伤可信度。E-CSG 做三件事：

1. **令牌桶**：容量 $b$、速率 $r$；每次"事件强制重观测"消耗 1 个令牌，无令牌则推迟到下一个块边界，用基础策略继续执行。
2. **重做上限**：每个子目标最多 `redo_cap` 次；超过则放弃该步、保前置分（与 SSG 一致），避免"反复重做"死循环。
3. **动作平滑**：恢复块与上一块做关节空间限幅/低通，避免动作统计规律性异常。

```python
class TokenBucket:
    def __init__(self, rate=2.0, burst=3.0):
        self.rate, self.cap, self.tokens, self.t = rate, burst, burst, None
    def allow(self, now):
        if self.t is not None:
            self.tokens = min(self.cap, self.tokens + (now - self.t) * self.rate)
        self.t = now
        if self.tokens >= 1.0:
            self.tokens -= 1.0
            return True
        return False
```

## 6. 保留组件在 v3 中的新角色

- **UIP-02′ SSG**：提供每个子目标的**分值 $s_g$**，是 EIPAR 期望损失公式的分子项；末步高分 → 优先监控。
- **UIP-11 GSO**：离线裁判 + **干扰注入器**，用于生成 E201–E206 的可用评估；仍只作"结构/顺序裁判"，不作成败裁判。
- **UIP-13 ACS**：从"按阶段选 k"升级为"**按事件活动度 + 画像风险选 k**"，是 SEF 产生实时收益的唯一通道。
- **UIP-14 MSGR**：技能图同时给出**区域掩码**（毛巾/拉链/锁/碗），让 SEF 只看任务相关区域，显著降假阳性；技能头提供逆操作恢复能力。
- **UIP-08′ LAT-ENG**：共享骨干、批处理、每端口隔离；事件突发时尤其需要端口级令牌桶。
- **UIP-05 LCAG**：未见物品/背景下的语义条件化，帮助验证器与技能图在泛化轴上不崩。

## 9. 合规、风险与未决项

- **单模型合规**：SEF 是确定性预处理（无参数）；HIP 是计数/贝叶斯统计（无参数）；事件检测头必须共享主干或从其蒸馏。若规则把任何额外可学习模块都算"第二模型"，则使用**纯规则版 SEF+HIP**，仍保留大部分收益。
- **无额外传感器**：本方案不依赖硬件事件相机；所有事件均来自接口已有 RGB 帧。若 `obs_delta_indices` 只允许单帧，则用跨调用环形缓冲，收益下降但不失效。
- **带宽/延迟红线**：不要为事件无限增加堆叠帧（每帧一张 JPEG）；建议 2–3 帧，并用 `image_resize` 控制成本。
- **画像循环性（最大科学风险）**：PEDF 的"人手"是脚本，HIP 的先验是文本，二者都可能"预测自己"。必须把 E210 的真机锚点作为放行条件。
- **画像不涉及个人隐私**：只统计任务/时机/逆操作，不存储身份信息；跨 episode 持久化仍需规则确认（E208）。
- **未决项**：① 评测是否允许多 episode 进程内持久状态；② 人为干扰是否正式计入；③ 控制频率/时限；④ 是否允许额外传感器。四项都待飞书手册公开后核实。
