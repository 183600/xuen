# 第 3 轮迭代（灵感循环 v3-WE：「全身控制」×「末端位姿」）—— 从「补数据」到「改坐标系」：让末端位姿成为任务不变量，让 pivot 成为低速全身调度器

> 本轮不是再加一条数据管线，而是修正一个**身体表征错配**。v2 把 G1 当「固定底座 + 双臂」，把 `pivot` 当噪声；本轮用公开数据证明：**接口真正可动的全身通道只有 `action.pivot[7]`，腰/腿只能观测、不能直接命令；而 `pivot` 在 20 个任务的公开演示里几乎恒定。** 因此「全身控制」在本赛题的正确形态不是 joint-space WBC，而是：① 用 `lower_body[15]` 重建躯干/相机位姿；② 用 `pivot` 做低速、稀疏、可验证的全身调度；③ 用**末端位姿**作为任务空间不变量，把全身冗余交给评测端 IK + 我们的可行域门控。
> **一句话判断：v2 在补数据，v3-WE 在改坐标系；前者抬高上限，后者降低方差。**

**本轮最强的三个新推论：**

- **R1（pivot 不是腰）**：`pivot` 是 **base 速度(3) + 躯干目标姿态(3, 假设) + 高度(1)**；腰关节 action 不在接口里。把 `pivot` 当腰角或把它置零，都是对接口的误读。真正可主动调的全身量是 base yaw、base 高度、以及小幅 base 平移。
- **R2（整身状态可重建）**：`lower_body[15]` 已足以重建 torso 位姿与头相机位姿（配合 URDF/标定）；因此「全身控制」的第一层价值不是控制，而是**把末端位姿表达在正确的身体参考系里**。
- **R3（EE 是任务不变量）**：任务成败由「夹爪相对物体/可供性」决定，而不是由臂关节角决定。选择 `ee` 控制空间，把逆解与躯干补偿交给评测端 IK；我们只负责**物体系/躯干系的 SE(3) 意图 + 可行域门控**。

## 2. 两个灵感词：直觉解释 → 严谨定义

### 2.1 全身控制

- **直觉**：人做桌面任务时，不会只动小臂。够不到会侧身、探腰、踮脚；看不清会转头/转身体；被推一下会用腿和腰稳住。G1 也有腰和腿，公开演示里它们确实在动——但**接口只给了一个 7 维 pivot 宏观量**，不给你 15 个下肢关节。
- **严谨定义**：设全身本体状态 `q_lb ∈ R^15`（6+6 腿 + 3 腰，已由 `lower_body` 给出），torso 位姿 `T_BT(q_lb) ∈ SE(3)`。动作侧的全身量只有 `u_p ∈ R^7`（pivot）。内部控制器 `C_int: (u_p, q_arm) → q_lb'` 是**不可见、不可直接反解**的植物（plant）。因此本赛题的"全身控制"= 在 `u_p` 上做**低速、稀疏、约束化**的宏观调度，同时用 `q_lb` 做**状态重建与扰动观测**；不是关节力矩/位置 WBC。

### 2.2 末端位姿

- **直觉**：夹爪"相对物体在哪里、朝哪个方向、开合多少"才是任务变量；臂角只是实现手段。物体被挪走时，正确反应是保持"相对物体"的位姿意图，而不是保持 base 系的绝对坐标。
- **严谨定义**：选定 `control_space="ee"`，动作是 `T_BE ∈ SE(3)`（base 系）。做两级分解：
  `T_BE = T_BT · T_TE = T_BO · T_OE`，
  其中 `T_BT` 由 `lower_body` 重建，`T_BO` 是物体/可供性系，`T_OE` 是**物体系中的末端位姿意图**。策略预测 `ΔT_OE`（6D 旋转表示 + 平移）与夹爪，而不是绝对 `T_BE`。这样当 base/腰移动或物体被挪动时，`T_OE` 保持不变，动作只需重投影。

## 3. 瓶颈假设（v3-WE）

- **H1（参考系错配）**：base 系 EE 位姿混入了"躯干在动"的 nuisance。在插网线、合盖、拉链这类 ±5 mm/±5° 决定成败的步上，不做躯干系规范化会系统性丢分。
- **H2（pivot 是低频冗余）**：base yaw 与高度是仅有的、可安全验证的全身冗余；它们能扩大可达域、把侧方目标转入双臂前方、把头相机对准遮挡区。但公开数据几乎不探索 pivot ⇒ 必须"默认锁死 + 影子模式 + 仿真辨识"。
- **H3（整身残差是虚拟力觉）**：接口没有力/触觉；`lower_body` 的"命令 vs 实测"残差、`T_BT` 的突变、EE 位姿的滞后，都是接触/推动的代理信号。
- **H4（开环块与移动躯干冲突）**：动作块是开环执行的；若块内 pivot/躯干在变，base 系 EE 目标会失配。因此 **pivot 只在块边界变更，块内冻结**；接触段用小块。
- **H5（ee 空间依赖评测端 IK）**：ee 模式把逆解交给评测端；若评测端 IK 不考虑腰/腿或与我们的 URDF 不一致，末端会偏。必须用 `ee_pose_gripper_base` 与 `_torso` 双标签做在线帧验证。
- **H6（数据空白）**：公开数据既无人扰、也几乎无 pivot 调制；任何"主动全身"结论都必须先 Gazebo（UIP-11）辨识，再真机影子验证，不能直接从数据外推。

## 4. 候选 → v3-WE 清单（详见产物区）

围绕两词发散 8 个草案，合并后得到：**旗舰 UIP-16 WB-TSP（全身感知的任务空间策略）**，由 **UIP-17 WBRR（全身可达域 + pivot 调度）** 提供冗余、**UIP-18 BAP（身体感知主动视觉）** 提供视角、**UIP-19 WBDO（全身扰动观测）** 提供恢复、**UIP-20 EECA（EE 空间自适应块长/接触柔顺）** 提供时序、**UIP-21 WBF-V（帧一致性验证）** 提供安检。v2 的 GSO/DRF/ACS/CSG 继续作为离线判分—造数据—控时—护栏四件套。

## 5. 本轮最大风险（一句话）

**若评测端的 `pivot` 语义与公开数据不同、或主动 base yaw/高度会破坏平衡/被规则禁止，则 UIP-17/18 的主动全身收益会大幅缩水——因此默认策略必须是「pivot 锁在任务默认值、仅 EE 位姿 + 躯干系规范化」，把 pivot 主动调制放在影子模式与 Gazebo 辨识之后再启用。**

**→ 本轮最值得押注：UIP-16 WB-TSP（物体系/躯干系 EE 位姿）× UIP-21 WBF-V（全身帧一致性验证）× UIP-19 WBDO（整身扰动观测）组成的"身体参考系闭环"**——它不依赖任何未公开的关节控制，完全落在 `ee` 动作空间与 `lower_body` 观测之内，却能直接吃掉位置泛化、人扰恢复与接触精度三条轴。

## 1. 【附产物】公开数据上的 pivot / lower_body 审计（2026-11-12）

> 样本：20 个任务；其中 ArrangePlates、ArrangeTestTubes、ColorArrangement、ConveyorSorting、DisconnectEthernet、FoldTowel、FruitCollection、HangCup、OrganizeBookshelf、PlugCharger、PlugInEthernet、PourOutMedicine、SyringeWaterTransfer、Unlock、ZipUp 各约 3000 帧；其余为 300 帧抽样。

### 1.1 已证事实

1. **`pivot` 的四个分量就是 base_command**：
   `action.base_command == action.pivot[:, [0,1,2,6]]`，在 20 个任务上 max abs diff = **0**。
   因此可确定：`pivot[0:3] = [v_x, v_y, ω_z]`（base 速度），`pivot[6] = h`（base 高度）。
2. **中间三维 `pivot[3:6]` 在任务内恒定**：多数任务为 `[0, 0.15, 0]`，FoldTowel 等为 `[0,0,0]`；与 `state_torso` 的 rpy 同量级。**假设 H-pivot：它是躯干目标姿态（roll, pitch, yaw），不是腰关节角。** 本方案不依赖这三维：默认保持任务常数。
3. **公开演示几乎不探索 pivot**：
   - `pivot[0:3]` 绝大多数为 0；唯一明显例外是 ConveyorSorting 的 base yaw，最高约 **0.8 rad/s**（抽样 10/3300 帧）。
   - base 平移（v_x, v_y）基本为 0；HangCup 有 0.003 m/s、Syringe 有 -0.011 m/s 的极小值。
   - `pivot[6]` 按任务固定：0.669–0.74 m（如 ArrangeTestTubes 0.682、Unlock 0.732、Syringe 0.731）。
4. **腰/腿在动，但不受 pivot 直接表达**：
   - 腰关节范围可达 yaw ~0.33 rad、pitch ~0.38 rad（OrganizeTools）；
   - 腿关节范围可达 ~0.2–0.35 rad；
   - 这些运动来自内部全身控制器，接口只暴露 `pivot` 宏观量与 `lower_body` 观测。
5. **`lower_body` 是完整全身状态**：
   - `lower_body[12:15] == waist_state_joint`（max diff 0）；
   - `lower_body[0:12] == left_leg + right_leg`（逐元素精确）；
   - `state_torso` 的位置在 episode 内近似恒定（~1e-3 m），其 rpy 与腰关节是置换/符号关系。
6. **头相机可由腰重建**：`state_d435` 的平移是腰 + 固定安装的刚体函数（E1 残差 ~1e-4–1e-5 m）；旋转存在约定差，需离线标定。
7. **EE 双参考系标签现成**：`*_ee_pose_gripper_base` 与 `*_ee_pose_gripper_torso` 成对出现，可直接监督 base↔torso 刚体变换。

|---|---|---|---|---|---|---|

## 2. 旗舰：UIP-16 · WB-TSP（Whole-Body-aware Task-Space Policy）

### 2.1 机制

1. **握手时选定 `control_space="ee"`**（不是运行期切换；UIP-10 的死因正是运行期切换）。动作是 base 系 EE 位姿 `T_BE ∈ SE(3)` + 夹爪；pivot 单独返回。
2. **身体参考系估计器**：从 `obs["observation.state.lower_body"]` 取 `q_lb`，用 URDF FK 得 `T_BT(q_lb)`；用离线标定得头相机 `T_BH = T_BT · T_TH`。同时可从 `left_arm/right_arm` + `T_BT` 正算 `T_BE`，与观测的 `ee_pose_gripper_base` 做一致性校验。
3. **物体系/可供性系**：`T_BO` 不依赖完整 CAD。对未见物体，用「抓取点 + 接近方向 + 局部主轴」定义**可供性系** `T_BO`（由语言 + 腕部 RGB 预测）；对已见物体可退化为 6D 位姿。
4. **策略输出**：`ΔT_OE`（物体系中的 EE 增量，旋转用连续 6D 表示）+ 夹爪开合 + 当前阶段标签。输入为 `T_TE = T_BT^{-1} T_BE`、`T_TO = T_BT^{-1} T_BO`、`q_arm`、`q_waist`、腕部/头部 RGB、语言。**输入/输出都不含 base 绝对坐标**，因此对 base/腰运动天然不变。
5. **投影与门控**：
   `T_BE^des = T_BO · T_OE^des`；
   若 `T_TE^des = T_BT^{-1} T_BE^des` 落在手臂可达域 `W_arm` 之外，则触发 UIP-17 的 pivot 调度或请求重观测；否则直接输出 `T_BE^des` 的块。

### 2.2 关键公式

- 正/逆投影：
  `T_TE = T_BT^{-1} · T_BE`
  `T_BE = T_BT · T_TE`
- 物体系意图：
  `T_OE = T_BO^{-1} · T_BE`
  `T_BE^des = T_BO · T_OE^des`
- 若 base/腰移动 `T_BT → T_BT'`，保持 `T_OE` 不变，则
  `T_BE' = T_BO · T_OE = T_BT' · (T_BT'^{-1} T_BE)`；
  策略只需在新观测上重算 `T_TE`，不需要重新学习绝对坐标。
- 若物体被挪动 `T_BO → T_BO'`，同样保持 `T_OE`，得到
  `T_BE' = T_BO' · T_OE`，实现位置泛化的"相对意图"。

### 2.3 与 v2 / 旁支的区别

- **v2 RHPV-D** 在图像/几何上验证子目标；WB-TSP 先**换控制变量**：把任务写成物体系 EE 位姿，再谈验证。
- **UIP-10** 死在"运行期切 space"；WB-TSP 在握手时**一次选 ee**，之后不再切。
- **只做 base→torso 换系的方案**（旁支 TAM）只改了输入；WB-TSP 同时改**输出**（物体系 `ΔT_OE`）、**可达域门控**与**扰动观测**，形成闭环。

### 2.4 可行性 / 资源

- **可行性高**：全部在 `ee` 动作空间与 `lower_body` 观测内；`ee` 模式是官方支持；无需额外接口、无需外部 VLM。
- **资源**：32 个公开数据集（标定 + 训练）；URDF（G1）；1 张推理卡；离线相机标定；Gazebo 仅用于 pivot 辨识与回放，不是必需。
- **落地步骤**：
  ① 用公开数据验证 `lower_body` → `T_BT` 的 FK，并与 `ee_pose_gripper_base` / `_torso` 对齐；
  ② 构建可供性系 `T_BO` 的弱监督（腕部 RGB + 语言 + 抓取点）；
  ③ 用 base/腰扰动做数据增强，训练物体系 `ΔT_OE` 策略；
  ④ 接入 WBF-V（UIP-21）与可达域门控（UIP-17）；
  ⑤ 在 Gazebo 中验证 pivot 响应，再真机影子测试。

## 3. UIP-17 · WBRR（Whole-Body Reachability Regulator）

### 3.1 pivot 的宏观语义

按已证分解：
`u_p = [v_x, v_y, ω_z, m_3, m_4, m_5, h]`
其中 `[v_x, v_y, ω_z, h] == base_command`（已证），`[m_3,m_4,m_5]` 为任务内恒定的躯干目标姿态（假设 H-pivot）。默认策略：**保持 `u_p = u_p^task` 不变**；只在可达域或可见性不足时，允许 **低速 base yaw / 高度** 调整。

### 3.2 可达域门控

定义手臂在躯干系的可达域 `W_arm`（可由 URDF 采样或公开数据拟合的椭球/凸包近似）。对每个预测意图：

```text
T_TE^des = T_BT^{-1} · T_BO · T_OE^des
d_reach = distance(T_TE^des, W_arm)          # 0 if inside
if d_reach > 0:
    solve Δu_p = argmin  ||Δu_p||^2 + λ_b||base_motion(Δu_p)||^2
                        + λ_c·occlusion(Δu_p)
                 s.t.  |v| ≤ v_max, |ω_z| ≤ ω_max,
                       |h - h0| ≤ h_max,
                       |m_i - m_i0| ≤ m_max,
                       T_BT(u_p + Δu_p) brings T_TE^des into W_arm,
                       no base translation inside table safety zone
```

- **优先顺序**：① 调 base yaw（最安全、公共数据有先例）；② 调高度；③ 最后才考虑小位移；④ 若都不行 → 不硬够，改为重观测/重规划。
- **影子模式（默认）**：`Δu_p = 0`，只输出 EE；记录"若允许 pivot 会怎么调"的日志，供离线评估。只有 Gazebo Pivot-ID 证明安全、且真机小样本验证通过后，才把 yaw/高度以极小步长启用。
- **块内冻结**：pivot 只在动作块边界变更；块内保持常数，避免开环执行时 base 系目标漂移。接触段块长更小（UIP-20）。

### 3.3 Pivot-ID（UIP-11 扩展）

公开数据几乎没有 pivot 变化，不能从数据学 `pivot → torso` 响应。用 Gazebo（`unitree_ros` 的 G1 + 关节控制器）做**受控阶跃/正弦**，辨识：
`T_BT(t+1) ≈ f(T_BT(t), u_p(t), q_arm(t), q_lb(t))`。
只辨识低频增益/延迟/限幅，不追求接触保真；输出用于 WBRR 的安全包络与超时保护。

### 3.4 风险

`pivot` 中间 3 维语义未公开；主动 base 运动可能被规则禁止或影响平衡。因此**默认锁死**；所有主动 pivot 必须经过 UIP-15 的预算（最大次数、最大速度、最小间隔）与 UIP-19 的扰动监测。

## 4. UIP-18 · BAP（Body-Aware Active Perception）

### 4.1 机制

- 由 `q_lb` 重建头相机 `T_BH`（平移残差已证 ~1e-4 m；旋转用离线标定）。因此**不需要接口给相机位姿**，也能知道"当前视角在哪"。
- 定义目标/可供性系在头相机与腕相机中的**可见性**：
  `vis = 1[target ∈ FOV] · 1[occlusion-free] · 1[projected_size ≥ s_min]`。
- 当两侧腕相机都看不到目标、或头相机被人体/机械臂遮挡时，触发**低速 base yaw/高度**（UIP-17）把目标转进头相机 FOV；近距离操作优先用腕相机，避免大范围动 base。
- 语言 + 可供性系用于区分"要看哪个物体"；时序上只在阶段切换/重观测时决策，不在块内频繁动。

### 4.2 与 v2 的区别

v2 的主动感知是隐含的（相机固定）；BAP 显式使用 `lower_body` 重建的相机位姿，并把"转身体看"变成一个可验证的宏观动作。它直接服务位置泛化（物体被挪到侧方）与人扰（人手遮挡）。

### 4.3 风险

动 base 会同时动相机和手臂；必须慢、小、可回退。遮挡检测依赖 RGB，透明/反光物体可能误判 ⇒ 用腕部多视角 + 时序一致性兜底。

## 5. UIP-19 · WBDO（Whole-Body Disturbance Observer）

### 5.1 机制

接口没有力/触觉，但有三类残差：

1. **躯干跟踪残差**：`e_T = log(T_BT^pred^{-1} · T_BT^obs)`。
   `T_BT^pred` 由上一帧 `T_BT` + pivot 命令 + 内部控制器模型前向得到；`T_BT^obs` 由 `lower_body` FK 得到。若 `||e_T|| > τ_T`，说明底座/躯干被人推动或内部控制器被扰动。
2. **EE 跟踪残差**：`e_E = log(T_BE^cmd^{-1} · T_BE^obs)`。用于检测被阻挡、滑移、插入失败。
3. **物体残差**：`e_O = log(T_BO^pred^{-1} · T_BO^obs)`。用于检测物体被拿走/挪动（v2 的撤回检测）。

融合规则（示例）：
```text
if ||e_T|| > τ_T and ||e_O|| < τ_O:   # 底座被推动，物体未动
    re-anchor T_BT; optionally counter with pivot yaw/height
elif ||e_O|| > τ_O:                   # 物体被挪走/撤回
    re-anchor T_BO; recompute T_OE
elif ||e_E|| > τ_E:                   # 手臂被挡/滑移
    back off along approach axis; retry from object frame
```

### 5.2 与 DCR-R 的区别

v2 DCR-R 主要靠视觉/几何检测"进度被撤回"；WBDO 增加**本体感觉的全身通道**，能捕捉"物体还在原地、但底座被推走"这种视觉不明显的扰动（T11/T25 的 human_* 明确包含"动底座"）。同时，`lower_body` 的腿/腰跟踪残差可作为**无力的接触代理**，与 v2 的步骤分安全网互补。

### 5.3 风险

内部全身控制器未知，`T_BT^pred` 会有模型误差；阈值需在公开数据 + Gazebo + 真机上分层校准。误报会导致无谓重做 ⇒ 用 UIP-15 限制重做次数，用 UIP-01′ 的置信度门限过滤。

## 6. UIP-20 · EECA（EE-space Adaptive Chunking + Contact Compliance）

### 6.1 机制

- **块长按阶段**：自由空间用大块（少往返、低延迟）；接触密集段（插网线、合盖、拉链、折叠）用小块（高频重观测、快纠错）。块长仍受 metadata 的 `action_chunk_size = K_MAX` 约束；每次可返回 `≤ K_MAX` 步。
- **EE 轨迹平滑**：在 `SE(3)` 上做带速度/加速度限制的插值，避免 rpy 跳变；输出连续 6D 旋转表示或等价的最小旋转插值。
- **接触柔顺**：没有力传感器，用"视觉/位姿柔顺"——当 `e_E` 残差持续超阈值时，沿接近轴后退 1–3 mm、横向螺旋搜索、再前进；在物体系内做，不依赖 base 绝对坐标。
- **块边界对齐**：pivot 变更、阶段切换、重锚定都只发生在块边界；块内保持 `T_BT`/`T_BO` 的假设不变。

### 6.2 风险

小块会增加往返与延迟暴露；评测端 IK 可能不接受过密的 EE 轨迹。需要 E115 测"块长–接触成功率–延迟"的 Pareto 前沿。

## 7. UIP-21 · WBF-V（Whole-Body Frame Verifier）

### 7.1 机制

在判进度之前，先做四系自洽检查：

1. **base↔torso**：由 `lower_body` 的腰 FK 得 `T_BT^FK`，与 `ee_pose_gripper_base`/`_torso` 双标签推出 `T_BT^ee` 比较；
2. **torso↔EE**：由臂 FK + `T_BT` 正算 `T_BE^FK`，与观测 `ee_pose_gripper_base` 比较；
3. **torso↔头相机**：由 `T_BT` + 离线标定预测 `T_BH`，与头相机图像中的已知标定物/目标投影比较；
4. **腕相机↔头相机**：对同一目标做三角化/重投影一致性检查。

任一残差超阈值 ⇒ 标记 `frame_suspect`，此时**不推进子目标**，只做重观测/标定恢复/保守等待；避免"帧错了还继续做"。

### 7.2 为什么必要

公开数据同时给 base/torso 双 EE 标签，说明官方也认为参考系是重要变量。接口只给 base 系 EE 与 `lower_body`，不给相机外参；若不验证，腰/头一动，几何判据就会系统性偏。WBF-V 是 UIP-01′ 的"安检门"。

```python
import numpy as np

class BodyFrame:
    """T_BT from lower_body; T_BH from calibration; T_TE from EE."""
    def __init__(self, urdf, cam_calib):
        self.fk = urdf; self.calib = cam_calib

    def from_obs(self, obs):
        q_lb = obs["observation.state.lower_body"]      # [15]
        q_arm_L = obs["observation.state.left_arm"]     # [7]
        q_arm_R = obs["observation.state.right_arm"]    # [7]
        T_BT = self.fk.torso(q_lb)                      # waist = q_lb[12:15]
        T_BH = T_BT @ self.calib.T_TH
        eeL = obs["observation.state.left_ee_pose_gripper_base"]
        eeR = obs["observation.state.right_ee_pose_gripper_base"]
        T_BE = { "L": se3(eeL), "R": se3(eeR) }
        return T_BT, T_BH, T_BE


class WBTSPolicy:                         # UIP-16 + 17 + 19 + 20 + 21
    def __init__(self, backbone, reach, governor, obs_verifier,
                 K_MAX=8, pivot_default=None):
        self.net = backbone; self.reach = reach
        self.gov = governor; self.ver = obs_verifier
        self.K_MAX = K_MAX; self.pivot_default = pivot_default
        self.reset()

    def reset(self):
        self.g = 0; self.track = None; self.pivot = self.pivot_default

    def get_action(self, obs):
        bf = BodyFrame.from_obs(obs)
        if not self.ver.ok(bf, obs):                  # UIP-21
            return self.safe_hold(obs)                # 不推进，只重观测

        # 1) 物体系意图：ΔT_OE（网络输入不含 base 绝对坐标）
        T_OE = self.net.predict_delta(obs, bf)        # UIP-16
        T_BE_des = bf.T_BO @ T_OE

        # 2) 可达域门控：必要时低速 pivot（默认影子模式 Δu_p=0）
        T_TE_des = inv(bf.T_BT) @ T_BE_des
        if not self.reach.inside(T_TE_des):
            self.pivot = self.gov.propose(bf, T_TE_des, self.pivot)

        # 3) 块长按阶段；块内 pivot 冻结
        k = self.net.phase_chunk(obs)                 # UIP-20
        k = min(k, self.K_MAX)
        ee_chunk = smooth_se3_chunk(T_BE_des, k)      # 速度/加速度限制
        grip = self.net.gripper(obs, k)

        # 4) 扰动观测在下一帧做（UIP-19）
        self.track = bf
        return {
            "meta.token": obs["token"],
            "action.left_ee_pose_gripper_base": ee_chunk["L"],
            "action.right_ee_pose_gripper_base": ee_chunk["R"],
            "action.left_gripper": grip["L"],
            "action.right_gripper": grip["R"],
            "action.pivot": tile(self.pivot, k),       # 块内常数
        }
```

```python
def wbdo(prev_bf, obs, pivot_cmd, ctrl_model,
         tau_T=1e-2, tau_E=2e-2, tau_O=2e-2):
    """UIP-19: whole-body disturbance observer (no force/tactile)."""
    bf = BodyFrame.from_obs(obs)
    T_BT_pred = ctrl_model(prev_bf.T_BT, pivot_cmd, obs)
    e_T = log_se3(inv(T_BT_pred) @ bf.T_BT)          # base/torso pushed?
    e_E = log_se3(inv(prev_bf.T_BE_cmd) @ bf.T_BE)   # blocked / slipping?
    e_O = log_se3(inv(prev_bf.T_BO_pred) @ bf.T_BO)  # object moved / withdrawn?
    flags = {
        "base_pushed":  norm(e_T) > tau_T and norm(e_O) < tau_O,
        "object_moved": norm(e_O) > tau_O,
        "arm_blocked":  norm(e_E) > tau_E,
    }
    return flags, (e_T, e_E, e_O)
```

```python
def reach_gate(T_TE_des, W_arm, pivot, governor):
    """UIP-17: only yaw/height by default; no translation in table zone."""
    if W_arm.contains(T_TE_des):
        return pivot, "ok"
    for axis in ("yaw", "height", "small_xy"):
        du = governor.best_step(T_TE_des, W_arm, axis)
        if du is not None and governor.safe(du):
            return pivot + du, axis
    return pivot, "infeasible"      # do not force; re-observe / re-plan
```

- **第 6–7 周**：EECA 块长/接触柔顺；用 Gazebo Pivot-ID 辨识 pivot 响应。
- **第 8 周**：影子 pivot 与 BAP 的离线评估；只对 base yaw/高度做小步长验证。
- **第 9 周起**：真机校准，逐步启用主动 pivot。

## 11. 合规与风险

- **单模型合规**：物体系策略、可达域头、阶段头共享同一条骨干；URDF FK、标定、pivot 护栏是解析/规则组件，不是额外大模型。
- **接口红线**：ee 模式只需返回 `action.left_ee_pose_gripper_base` / `right...` + `pivot` + grippers + token；不得返回腰/腿关节 action（接口没有）。块长、dtype、shape 严格按 README §3。
- **规则风险**：主动 base 运动是否被允许、是否影响平衡/时限，手册仍未取到；默认影子模式，主动 pivot 作为可开关的增益项。
- **参考系风险**：URDF 与评测端 IK 可能不一致；WBF-V 用观测 EE 做在线校验，残差大时退回 base 系保守控制。
- **数据风险**：公开数据零 pivot 探索、零人扰；所有主动 pivot/WBDO 阈值必须仿真 + 真机分层校准。
- **过拟合风险**：物体系可供性估计可能对未见物体过拟合；用语言条件化 + 几何先验 + 多视角一致性兜底。

## 12. 本轮最大风险 & 押注

**一句话**：如果评测端的 `pivot` 语义与公开数据不同、或主动 base yaw/高度被规则/平衡限制，UIP-17/18 的主动全身收益会缩水；因此基线必须坚持「pivot 默认锁死 + EE 物体系位姿 + 帧验证」，把 pivot 主动调制当作可回退的增益，而不是前提。

**→ 押注：UIP-16 WB-TSP × UIP-21 WBF-V × UIP-19 WBDO 的「身体参考系闭环」**——它不依赖未公开的关节控制，完全落在 `ee` 动作空间与 `lower_body` 观测之内，却同时命中位置泛化、人扰恢复、接触精度三条轴；pivot 主动调度只作为经 Gazebo 辨识后的可选放大器。
