# 第 41 轮 · 双灵感落地 v18：臂-树共设计（ARM-BT）——把计划编译成可验证、可恢复、省步数的手臂行为树（四层架构 v6）

> 承接第 40 轮（v17：热预算治理 × 步数感知规划 × 学习-TO 混合轨迹，四层架构 v5）。本轮灵感词「机械臂 / 行为树」。这两个词不是「再加两个模块」：v17 的 IP-49 只产出计划，IP-50 只精修单段轨迹，二者之间缺一个**可反应、可恢复、可验证的执行结构**；同时 v17 把双臂当成 14 个关节的目标生成器，忽略 7-DoF 冗余、奇异、自碰、换臂与 pivot 的可达性——很多「规划失败」其实是**臂不可行**。本轮把两词合成一个双层控制器：**行为树是离散策略层，机械臂是连续约束层，技能契约（skill contract）是二者的接口**。v18 的主轴从「会规划」转向「**每个 tick 都可执行、每次失败都可局部恢复、每步都可追溯**」。公开数据也恰好补齐了 v17 的两个空白：32 个任务数据集（约 32k episodes / 169h，LeRobot v3.0，30fps，joint+EE+lower_body+pivot）公开可发现，使技能图、姿态先验、时长/成功率先验从「估计量」变成「可测量」。

## 0. 联网核实（先事实后推理；检索口径 2026-11-10，来源链接见产物区 §5）

- **事实 F67（官方任务集与榜单，https://unibot.unitree.com/challenges.html、/leaderboard.html，2026-11-10）**：UniBot-V1 挑战赛含 **32 项真实桌面操作任务**，官方统计 **32000 条演示样本、169 小时数据**；任务页每题标注「得分点（满分 100）Scoring Steps (100 pts)」；排行榜明示「按平均成功率与步骤分综合排序」，当前仍为「即将发布 Coming Soon」。**A39**：两列的权重、success 与 step 的优先级、跨任务聚合公式仍未公开。
- **事实 F68（HF 任务数据集集合，https://huggingface.co/collections/unitreerobotics/unibot-v1-challenge-dataset，2026-11-10）**：集合页公开列出 **32 个单任务数据集**，每个约 969–1530 条示范，合计约 32k；任务覆盖抓取/放置/双手协调/可变形物/精密插入/长程整理。可读出的任务名包括：HangCup、ArrangePlates、ArrangeTestTubes、ZipUp、ColorArrangement、Unlock、DisconnectEthernet、ConveyorSorting、FruitCollection、FoldTowel、OrganizeBookshelf、FruitSorting、SpellRobot、OrganizePencilCase、OrganizeStationery、StackBowls、StoreCups、OrganizeTools、PackDoll、PackBag、PackPhone、StoreEarphones、StorePaddle、PaperCupStacking、PickOutBatteries、ToolboxStorage、PlugCharger、SyringeWaterTransfer、PlugInEthernet、PlacePhotoFrame、RemovePinnedNote、PourOutMedicine。
- **事实 F69（数据字段与规模，单任务页与 meta，如 https://huggingface.co/datasets/unitreerobotics/G1_Dex1_PlugCharger，2026-11-10）**：数据集为 LeRobot v3.0、Apache-2.0、30fps、相机 480×640×3（head_stereo_left/right + wrist_left/right）；观测含左右臂 7、夹爪 1、lower_body 15、EE 位姿（base/torso 各 6）、waist 3、torso 6、D435 6；动作含 joint/EE/lower_body/waist/torso/base_command/pivot/gripper_controls。PlugCharger 为 1022 episodes、463451 frames（约 453 帧/条，≈15.1s @30fps）。**通道诚实**：在线接口只暴露其中子集（F60），离线字段更丰富；这些数据只能做离线先验/辨识，不能当测试时输入。
- **事实 F70（对 v17 F61 的修正）**：v17 依据聚合 API 401 判定「挑战数据集门控」。本轮实测：集合页可读，单任务页 `repoIsGated:false`，README/info.json/stats.json/tasks.parquet 与 parquet 分片均可访问（单文件约 100MB，LFS/CDN 200）。因此更准确的说法是：**旧的聚合端点/匿名 API 会 401，但 32 个任务数据集是公开可发现的**。这把 v17 的「无官方数据源」从阻塞项降级为「成功示范可用、失败/扰动标签仍缺」。
- **事实 F71（行为树与臂控制的经典依据，记忆级，本轮未逐篇 API 复核）**：行为树提供模块化、反应式、可组合的离散执行语义（Sequence/Fallback/Parallel/Decorator/Retry），适合把计划与失败恢复写在同一结构里（Colledanchise & Ögren, *Behavior Trees in Robotics and AI*, 2018；Marzinotto et al., ICRA 2014；Iovino et al. 综述）。机械臂 7-DoF 冗余、可操作度、任务优先级与双臂协同是成熟控制问题（Yoshikawa 1985；Khatib 1987；Nakamura 1987）。本轮的新意不在这些工具本身，而在**把臂可行性写成 BT 叶子的硬前置条件，并用公开示范标定姿态/时长先验**。
- **事实 F72（官方接口复核，F60 仍成立）**：提交仓库确认 `metadata/get_action/reset`、4 相机、joint/ee 互斥、gripper、pivot、`action_chunk_size=T_a`、N 台测试机固定端口从 8765 起连续、不同端口可能并发、共享后端须并发且每端口 reset/历史隔离；每步时延与动作统计规律性会被记录为可信度依据。**A40**：N 的具体值、评测机 GPU 权限、在线是否提供 torso/D435 等额外状态仍未公开。

## 1. 研究者直觉（先直觉与动机，后形式化）

**直觉 1（机械臂：v17 把最难的连续约束当成了已解决）**。v17 的 IP-50 在 14 维关节/6D EE 上做 TO，但默认「目标可达、姿态可解、双臂不碰、腕部不挡、奇异不出现」。现实是：G1 每臂 7 DoF，桌面任务里同一 EE 位姿有一整族关节解（肘上/肘下、腕翻转、肩偏置），不同解的可操作度、关节余量、自碰距离、力矩/热、腕相机遮挡差异巨大；双臂共享胸/腰/pivot 时还会互相抢工作空间。很多「抓取失败」不是语义错，而是**选了一个坏姿态**：接近奇异时跟踪误差放大、腕部相机被自己挡住、肘部撞到桌面/另一臂、或者为了够到目标把关节顶到限位。**机械臂在本轮不是硬件背景，而是一个可优化的离散-连续决策变量**；公开数据的 joint-EE 对还允许我们在没有 URDF 的情况下拟合 FK/IK 与姿态先验（A17 的缓解从「等 URDF」变成「从数据辨识」）。

**直觉 2（行为树：v17 的执行是脚本，不是控制器）**。v17 的 IP-49 产出计划后，运行时是一个带 if/else 的循环：失败→全局重规划/调用 LLM。这在 5 类泛化场景下很贵：对象被移动、夹爪滑脱、人把物体拿走、腕相机被挡——这些都是**局部可恢复**的，却每次都要重新规划，吃步数、吃时延、吃热预算。行为树把「计划 + 恢复」写成一个可检查的结构：Sequence 是计划，Fallback 是失败升级，Guard 是前置/后置条件，Retry 是局部重试，Parallel 是双臂协同，Decorator 是 Δ-Plane 预算。它的价值不是「新」，而是**把恢复从规划器里拿出来，变成 O(1) tick 的运行时行为**；同时 tick 天然是步数记账单位，能让「省步数」变成结构性质而不是事后统计。但必须记住前车之鉴：没有臂可行性的 BT 只是把脚本换了个树形写法。

**直觉 3（两词咬合：技能契约是离散与连续的接口）**。BT 的叶子不能是「一个 VLA 调用」这么粗的粒度，也不能是「一条固定轨迹」这么死的粒度；它应该是一份**技能契约**：语义前后置条件（来自 IP-36 语义图/图世界模型）+ 任务空间目标 + 臂模式（左/右/双臂、肘上/肘下、抓取方向、pivot 是否移位）+ 可行性约束（关节限位、自碰、物体包络、力矩/热）+ 成本模型（期望步数、时延、热量、成功率）+ 失败模式与恢复句柄。BT 选离散契约（哪个技能/哪条臂/哪种姿态/pivot 是否动），臂控制器在契约内解连续冗余（QP/TO）。**没有契约，BT 会规划出臂做不到的技能；没有 BT，臂只能在一条错误的任务上做局部最优。** 两词合起来才是完整的执行层。

**直觉 4（公开数据改变了 v17 的风险结构）**。v17 自述最大风险是「p_s 先验无官方数据源」「URDF/跟踪模型未备」。本轮核实发现：32 个任务数据集在 HF 集合页公开可发现，单任务页 `repoIsGated:false`、Apache-2.0、LeRobot v3.0，README/info/stats/tasks/parquet 均可访问；每任务约 970–1530 条成功示范，总计约 32k episodes / 169h。这至少能做四件事：(a) 从 EE 速度/夹爪开合/pivot 变化做变点分割，挖出技能段与技能转移图，给 BT 模板和 p_s 先验；(b) 从 joint-EE 对拟合 FK/IK 与各技能的姿态分布，给臂可行性/姿态先验；(c) 从 episode 长度估计每技能时长与步数预算，校准 IP-49 的 g(N)；(d) 从任务名与语言指令建立 32 任务的技能本体。**但要诚实**：数据只有成功示范、没有失败/扰动标签；测试集仍隐藏；离线数据字段比在线观测丰富（在线没有 torso/D435/waist 全量），所以它只能做离线先验，不能当测试时输入。

**直觉 5（修剪：v17 的四个「能力展示型」设计现在可以被替代）**。(a) IP-45 服务网格剩下的注册/契约/网关/追踪——BT 运行时 + 单个 PolicyService 已经承担了技能组合与故障转移，服务网格是重复抽象；(b) IP-42 跨本体运动——赛题只有 G1，公开数据也是 G1/Dex1，跨本体预训练的边际得分最低；(c) IP-46 的 Lipschitz/对抗半径——非线性闭环上保守且不可操作，保留 CBF + 热稳态 SLO 即可；(d) IP-26 的物理增广轴——有了 32k 真机示范，域随机化的边际收益下降，保留视觉/语言增广即可。**本轮把 IP-39 也合并进 IP-52（中层任务-运动 = BT 编译 + 技能契约），使 P0 核心回到 6 项：IP-48/49/50/51/52/21。** 这是「以删代加」的深化。

## 2. 灵感词 → 落地线（新增 + 重构 + 修剪登记）

- 「**机械臂**」→ **IP-51 ARM-SKILL-CONTRACT（ASC，P0 新增）**：技能契约库（语义前后置 + 任务目标 + 臂模式 + 可行性约束 + 成本模型 + 恢复句柄）+ 7-DoF 冗余解析 QP + 双臂协同 QP + pivot 移位选择 + 从公开示范拟合的 FK/IK 与姿态先验 + 可操作度/奇异/自碰/关节余量/力矩热度量。
- 「**行为树**」→ **IP-52 EMBODIED-BEHAVIOR-TREE（EBT，P0 新增，合并 IP-39）**：把 IP-49 的 E_score 计划编译成行为树；Sequence 是计划、Fallback 是失败升级、Guard 是前后置条件、Retry 是局部重试、Parallel 是双臂协同、Decorator 是 Δ-Plane 预算；BT 是运行时执行器，全局规划只在语义失败或 BT 耗尽时触发；含编译正确性/进度/安全/步数经济性论证。
- 「**数据**」→ **IP-53 SKILL-GRAPH-INDUCTION（SGI，P1 新增）**：从 32 任务 × 约 1000 条成功示范中做变点分割、技能聚类、技能转移图、姿态/时长/成功率先验；为 IP-51 初始化契约、为 IP-52 提供模板、为 IP-49 提供 p_s 与步数预算。离线管线，不进入测试时推理。
- 升级：**IP-49**（输出 plan + BT 模板 + 契约需求；吃 SGI 的 p_s/时长先验）、**IP-50**（TO 在契约内精修；冗余 QP；可行性硬约束；双臂相对位姿约束）、**IP-43**（流式执行 = BT tick 引擎；chunk 截断由 guard 触发）、**IP-48**（Δ-Plane 三账本变成 BT 的 Decorator，不新增账本）、**IP-36**（语义图提供前后置谓词与物体包络）、**IP-35**（MuJoCo 预校验契约）、**IP-24/38**（失败信号 = BT fallback 触发）、**IP-33**（叶子级 CBF）、**IP-25**（SLO 纳入 tick/编译时延）、**IP-21**（单模型旗舰 + 单 PolicyService）。
- 修剪登记：**IP-39 HIERARCHICAL-TASK-MOTION → 合并进 IP-52**（BT 编译器承担 waypoints/约束/权重输出，不再保留独立中层）；**IP-45 SKILL-SERVICE-MESH → P2**（BT 运行时 + 单服务替代注册/契约/网关/追踪）；**IP-42 CROSS-EMBODIMENT-MOTION → P2**（单一 G1 + 公开 G1/Dex1 数据，跨本体边际低）；**IP-46 的 Lipschitz/对抗半径 → P2**（保留 CBF + 热稳态 SLO）；**IP-26 的物理增广轴 → P2**（保留视觉/语言轴）；**IP-44 完整三阶段蒸馏 → P1 简化**（公开数据 + LoRA/技能条件微调，不再把 MAML 作为 P0 路径）。

## 3. 形式化直觉（严格版见产物区 §3）

**定义 29（技能契约）**：一份契约 `C=(name, pre, post, goal, mode, Θ, Φ, cost, recover)`：`pre/post` 是语义状态（IP-36 的谓词）与臂状态的合取；`goal∈SE(3)`（或相对位姿）；`mode∈M={L,R,B}×{elbow-up,elbow-down}×{top,side,front}×{pivot-shift 0/1}`；`Θ` 是可行关节集；`Φ` 是约束集（关节限位、自碰、物体包络、速度/力矩）；`cost=(E[steps], E[∫τ²dt], E[latency], p_success)`；`recover` 是有限个恢复契约。**可采纳**：`pre(s)` 成立且存在轨迹满足 `Φ`、终止于 `goal`、可行性裕度 `φ≥0`。

**定义 30（臂可行性裕度，不作为第四本账）**：`φ(q,g)=min{α_m(w(q)-w_min), α_s(σ_min(J(q))-σ_min), α_j min_i((q_i-q_i^min)/Δ,(q_i^max-q_i)/Δ), α_c(d_self(q)-d_min), α_τ(τ_max-‖τ(q)‖)}`，其中 `w(q)=√det(JJᵀ)` 为可操作度，`σ_min(J)` 为奇异裕度，`d_self` 为自碰距离，`τ` 为逆动力学力矩。**φ 是硬约束面，不是优化目标**；它同时防止「为了省步数而选不可行姿态」和「为了可行而无限绕路」。

**定义 31（行为树语义）**：节点 tick 返回 `Success/Failure/Running`；Sequence 依次执行、Failure 传播；Fallback 依次尝试、Success 短路；Parallel 按成功/失败策略同步；Decorator 含 Retry/Guard/Timeout/Invert；Condition 只读状态；Action 叶子执行一个技能契约的一段 chunk。BT 是**反应式程序**：guard 可在不调用规划器的情况下切换分支。

**定义 32（EBT 编译）**：给定计划 `π=(s_1…s_n)` 与契约库，编译 `T=Seq(BudgetGuard, τ_1,…,τ_n)`，其中 `τ_i=Retry(Fallback(GuardPost(C_i), recovery_{i,1},…,recovery_{i,k}), r_i)`；每个 `C_i` 内用 `Selector` 按成本排序臂模式；双臂技能用 `Parallel` 加相对位姿约束；全局 `Decorator` 挂热/时延/步数预算。**编译正确性**：(P51) 无 guard 失败时，BT 的 chunk 序列与计划一致、步数不增；(P52) 每个叶子失败都有恢复路径，且 fallback 边使一个良基测度下降 ⇒ 无死锁；(P53) 每个叶子带 CBF/热/时延 guard，违规返回 Failure 而非动作 ⇒ 组合安全；(P54) 局部恢复的期望步数不高于全局重规划（在失败率 p 下 `E[N]≤N_plan+p/(1-p)c_rec`）。

**定义 33（BT 即半马尔可夫选项）**：每个契约为一个 option `(I_C, β_C, cost_C)`；BT 定义一个分层策略。运行时只优化有限个 BT 变体（技能变体/臂模式/fallback 顺序），用近似策略迭代或 bandit 更新，**不做端到端 RL**——这是数据效率的关键。

**定义 34（示范诱导技能图）**：对每条示范 `τ`，用变点检测把 `[0,T]` 分成技能区间，聚类得到技能集 `S`，建转移图 `G_skill`；估计 `p(s|task)`、`p(s'|s)`、时长分布、姿态分布 `p(q|s,goal)` 与可行性统计。它给 IP-51/52/49 提供先验，但不改变在线接口。

## 4. 关键决断

1. **两层一契约**：BT 负责离散策略与恢复，臂 QP/TO 负责连续可行；技能契约是唯一接口，禁止 BT 直接输出未校验的关节目标。
2. **可行性是硬前置**：`φ<0` 的技能变体不进入 BT 选择；宁可让 BT 失败并上交全局规划，也不输出不可行动作。
3. **BT 是编译产物**：不手写 32 棵树；由 E_score 计划 + 契约库 + 场景画像编译，失败记忆只改 fallback 顺序/变体选择。
4. **局部恢复优先，两次失败即上交**：局部 fallback 省步数/时延/热，但设「同一叶子连续失败两次或 BT 耗尽 → 全局重规划」的硬逃逸，防止局部最优。
5. **数据只做先验**：32 任务公开示范用于 SGI/FK-IK/时长校准；不在测试时读取离线字段，不做「用训练集泄漏测试集」的事。
6. **以删代加**：IP-39 合并、IP-45/42/46 部分/26 部分降 P2，P0 核心回到 6 项。

## 5. 本轮最大风险（一句话）

**技能契约与臂可行性模型都从成功示范归纳，若测试扰动落在示范支撑集之外，BT 会把「不可行/未见过」误判为「可恢复」，用局部 fallback 反复尝试而拒绝全局重规划，反而比 v17 更浪费步数与热预算；必须以 E73–E77 五重守门，并保留「同一叶子连续失败两次即上交全局规划器」的硬逃逸。**

# 第 41 轮产物 · 创新点清单 v18：臂-树共设计 ARM-BT（技能契约 × 行为树编译 × 示范诱导技能图，四层架构 v6）

> 承接 v17（第 40 轮：Δ-Plane × E_score 规划 × 学习-TO）。本轮灵感词「机械臂 / 行为树」。v17 把「计划」和「单段轨迹精修」都做到了，却没有回答两个执行层问题：**计划失败后除了全局重规划还能做什么？臂在当前位姿/关节解下真的做得到吗？** 本轮新增 **2 项 P0 核心 IP（IP-51 臂技能契约 / IP-52 具身行为树）+ 1 项 P1 数据引擎（IP-53 示范诱导技能图）**，**把 IP-39 合并进 IP-52**，并 **将 IP-45 服务网格、IP-42 跨本体、IP-46 的 Lipschitz/对抗半径、IP-26 的物理增广轴降为 P2**。P0 核心收敛为 6 项：**IP-48 / IP-49 / IP-50 / IP-51 / IP-52 / IP-21**。同时修正 v17 的 F61：32 个任务数据集是公开可发现的（单任务页 `repoIsGated:false`、Apache-2.0、LeRobot v3.0），这使「技能图、姿态先验、时长/成功率先验」第一次有真实数据可标定。

## 0. 结论

- **ARM-BT 主轴**：行为树（离散策略/恢复）与机械臂（连续可行性/冗余）不是两个模块，而是**同一执行层的两面**；技能契约是唯一接口。运行时每个 tick 先过契约前置与臂可行性 `φ≥0`，再执行 chunk；失败走局部 fallback，连续两次失败才上交全局规划。
- **IP-51 ARM-SKILL-CONTRACT（P0 新增）**：技能契约库 + 7-DoF 冗余 QP + 双臂协同 QP + pivot 移位 + 从公开示范拟合的 FK/IK 与姿态先验；把可操作度、奇异、自碰、关节余量、力矩/热作为硬约束；直接缓解 v17 的「URDF 不可得」「末端精度」「长时程姿态漂移」。
- **IP-52 EMBODIED-BEHAVIOR-TREE（P0 新增，合并 IP-39）**：把 IP-49 的 E_score 计划编译成 BT；Sequence=计划、Fallback=失败升级、Guard=前后置、Retry=局部重试、Parallel=双臂、Decorator=Δ-Plane 预算。给出计划保持、无死锁、组合安全、步数经济性四条论证；BT 是运行时控制器，不是第二个规划器。
- **IP-53 SKILL-GRAPH-INDUCTION（P1 新增）**：从 32 任务 × 约 1000 条成功示范中做变点分割、技能聚类、转移图、姿态/时长/成功率先验；离线运行，给 IP-51/52/49 提供初始契约与先验，不进入测试时输入。
- **修剪/合并**：IP-39 → 合并进 IP-52；IP-45 SKILL-SERVICE-MESH → P2（BT + 单 PolicyService 替代）；IP-42 CROSS-EMBODIMENT → P2（单一 G1）；IP-46 的 Lipschitz/对抗半径 → P2（保留 CBF + 热稳态 SLO）；IP-26 的物理增广轴 → P2（保留视觉/语言轴）；IP-44 完整三阶段蒸馏 → P1 简化（公开数据 + LoRA/技能条件微调）。
- **事实修正**：F68/F69/F70 显示 32 个任务数据集公开可发现、字段与规模可读；v17 的「数据集整体门控」应降级为「聚合端点匿名 401，任务数据集公开」。但数据只有成功示范，失败/扰动标签仍缺（A41）。
- **行动项**：A16–A38 延续；新增 A39（榜单聚合公式）、A40（N/遥测/在线额外状态）、A41（失败/扰动标签缺失）、A42（示范-评测分布差）、A43（FK/IK 从数据辨识的误差界）。

### 3.2 IP-51 ARM-SKILL-CONTRACT（ASC，臂技能契约，完整设计）

**IP 卡片（六字段）**：
- **动机**：F69 的 joint-EE 对证明同一 EE 目标有多族关节解；v17 的 IP-50 只优化轨迹，未把「选哪族解/哪条臂/是否移 pivot」作为离散决策；桌面任务中的抓空、自碰、奇异抖动、腕相机遮挡、关节限位很多是姿态选择错误，而非语义错误。
- **与现有方案差异**：VLA/TO 通常把臂当 6D/14D 目标生成器；BT 文献有技能/条件但少有「臂可行性硬前置」；数据驱动操作策略少有把示范姿态先验与在线 QP 结合。ASC 把三者合成**可采纳契约**：先判可行，再选变体，再解连续冗余。
- **技术可行性**：7-DoF QP 在 CPU 上 <1ms；FK/IK 可从 F69 的 joint-EE 对拟合（无需 URDF）；MuJoCo/URDF 仅作可选校验；姿态先验可用最近邻/小 MLP；双臂相对位姿约束是标准 QP。
- **所需资源**：数据=32 任务示范（F68/F69，离线）；算力=QP <1ms/次、契约选择 O(|M|)；接口=官方 joint/ee 目标 + pivot + gripper；无新接口。
- **落地步骤**：① 用 SGI（IP-53）分割技能并统计姿态/时长；② 拟合 FK/IK 与 `φ` 的代理模型；③ 实现单臂/双臂 QP；④ 契约库入库（pre/post/goal/mode/cost/recover）；⑤ 与 IP-50/IP-52 联调；⑥ E73/E74 验收。
- **风险**：成功示范无失败标签→契约恢复靠扰动/仿真补；FK/IK 拟合误差→保守 `φ` 裕度 + CBF；双臂耦合→相对位姿约束 + 优先级；姿态先验分布外→在线探索少量变体并记录。

**单臂冗余 QP（契约内连续层）**：

```
min_{q̇,δ}  ½‖q̇ − J⁺(ẋ_d + K e)‖²
          + ½ w_m (w_min − w(q))²_+ + ½ w_j Σ_i [(q_i−q_i^min)²_+ + (q_i^max−q_i)²_+]
          + ½ w_c (d_min − d_self(q))²_+ + ½ w_τ ‖τ(q,q̇)‖²
s.t.      q̇ ∈ [q̇_min, q̇_max],  q + Δt·q̇ ∈ [q_min, q_max]
          可选：末端包络/物体包络 d(x,𝒪) ≥ margin
```

- 目标函数前两项是主任务 + 可操作度/限位/自碰/力矩的软惩罚；`δ` 用于硬约束松弛，**若松弛后仍不可行，返回 `Infesible` 给 BT，而不是输出坏动作**。
- `w_τ‖τ‖²` 与 IP-48 的电机热代理 `∫τ²dt` 同源：选低力矩姿态=降温升；`w(q)` 与 `σ_min` 防奇异；`d_self` 防双臂互撞；关节余量防长时程漂移。
- **pivot 作为离散动作**：若当前臂模式在所有 `q` 上 `φ<0`，BT 的 `Selector` 可插入 `PivotShift` 叶子（移动底盘/腰），其成本 = 额外步数 + 时延 + 热；只有当 `E_score` 增益 > 成本时才选。

**双臂协同 QP**：

```
min_{q̇_L,q̇_R}  Σ_{a∈{L,R}} [单臂目标] + w_rel‖log(T_L⁻¹T_R) − log(T_rel^des)‖²
                + w_f‖f_L+f_R−f_obj‖² + w_int‖f_int‖²
s.t.            单臂约束；相对位姿约束；夹爪时间窗；pivot 准静态
```

- 相对位姿约束用于交接/共同搬运/拧盖；`f_int` 正则抑制内力；若一手失败，BT 进入 `Parallel` 的降级分支（另一手保持/撤回），而不是整棵树失败。

**数据先验（缓解 A17/A43）**：
- 用 F69 的 `(q, x)` 对拟合 FK：`x̂=FK(q;θ)`，最小化 `‖log(x̂⁻¹x)‖²`；`θ` 含连杆长度/关节偏置/基座变换。若拟合残差 < 5mm/0.5°，则可替代 URDF 做可行性判断；否则降级为「关节限位 + 粗姿态先验 + CBF」。
- 每个技能簇 `s` 估计 `p(q|s,goal,context)`（最近邻/高斯/小 MLP）；作为 QP 初值与正则，减少奇异/跳变。
- 估计每技能时长分布（F69 帧数/30fps）与成功率，作为 IP-49 的 `g(N)`/`p_s` 初值；这是 v17「p_s 先验无数据源」的直接缓解。

**正确性论证**：
- **P55（可行性）**：若 `φ(q,g)≥0` 且跟踪误差有界（E38），则 QP 解满足关节/自碰/包络约束；CBF（IP-33）兜底。
- **P56（姿态不劣）**：在可行集内，QP 的二次目标包含可操作度/限位/力矩项；其最优值不劣于固定名义姿态（后者是可行集的一个点）。
- **P57（数据先验不破坏可行性）**：姿态先验只作为初值/正则，硬约束仍由 QP/φ 保证；分布外时退化为「限位 + CBF」。

### 3.3 IP-52 EMBODIED-BEHAVIOR-TREE（EBT，具身行为树，完整设计）

**IP 卡片（六字段）**：
- **动机**：v17 失败处理是全局循环；5 类泛化场景中大量失败是局部可恢复的（物体被移动、夹爪滑脱、遮挡、人的干扰），全局重规划吃步数/时延/热；BT 把恢复变成 O(1) tick。F67/F68 的 32 任务结构为 BT 模板提供先验。
- **与现有方案差异**：前序 CHRONO-BT 把评分文本编译成 BT，但没有臂可行性，容易变成「脚本树」；EBT 编译的是 **E_score 计划 + 技能契约**，每个叶子先过 `pre ∧ φ≥0`，fallback 由失败记忆/场景策略生成；BT 不是第二个规划器，语义仍归 IP-49。
- **技术可行性**：BT 是确定性代码，tick O(depth)，编译离线；与 PolicyService 单进程兼容；无需额外大模型；可用现有 Python BT 库或自写 200 行状态机。
- **所需资源**：契约库（IP-51）、GWM/语义图（IP-36）、失败记忆（IP-49）、Δ-Plane（IP-48）；算力可忽略（编译 <50ms，tick <1ms）。
- **落地步骤**：① 定义节点库与契约接口；② 实现编译器（plan→BT）；③ 实现运行时（tick/guard/chunk 截断/两击逃逸）；④ 失败记忆→fallback 排序；⑤ 组合验证/故障注入；⑥ E75/E76 验收。
- **风险**：BT 过刚→全局规划逃逸；局部最优→两击逃逸；验证状态爆炸→只做局部 assume-guarantee；tick 抖动→chunk 边界 tick + 预编译。

**节点语义表**：

| 节点 | Success | Failure | Running | 备注 |
|---|---|---|---|---|
| Sequence | 全部子节点 Success | 任一 Failure | 当前子节点 Running | 计划主链 |
| Fallback | 任一子节点 Success | 全部 Failure | 当前子节点 Running | 失败升级 |
| Parallel | 按策略（all/any） | 按策略 | 任一 Running | 双臂/监控 |
| Retry(k) | 第 ≤k 次 Success | k 次 Failure | 正在重试 | 局部重试 |
| Guard(pre/post) | 条件满足才 tick 子节点 | 条件不满足 | — | 前后置/预算 |
| Timeout(Δ) | 子节点 Success | 超时 | 子节点 Running | 时延守护 |
| Selector | 按成本选第一个可行变体 | 无可行变体 | — | 臂模式选择 |
| Action(C) | 契约 post 满足 | 契约失败/φ<0 | chunk 执行中 | 叶子 |

**编译算法（plan → EBT）**：

```
输入：E_score 计划 π=(s_1…s_n)、契约库 L、语义状态 σ、失败记忆 M_f、Δ-Plane 预算 b
输出：行为树 T（可执行/可验证）

1. root ← Seq(BudgetGuard(b), ProgressGuard(goal))
2. for s_i in π:
     V_i ← {C ∈ L.variants(s_i) | C.pre(σ) ∧ φ(q,C.goal) ≥ 0}   # 硬前置
     if V_i = ∅:
         return Fallback(Replan(s_i), PivotShift/AlternativeArm)  # 不输出不可行叶子
     leaf_i ← Selector(sort_by_cost(V_i))                          # 臂模式/姿态选择
     rec_i  ← Fallback(M_f.recoveries(s_i), GenericRecoveries)     # 失败升级
     τ_i    ← Retry(GuardPost(C_i, Fallback(leaf_i, rec_i)), r_i)
     root.add(τ_i)
3. if 双臂任务: root.add(Parallel(τ_L, τ_R, rel_pose_constraint))
4. root.add(Decorator(ThermalGuard, LatencyGuard, StepGuard))     # Δ-Plane
5. return CompileToStateMachine(root)                              # 部署时扁平化
```

- **局部恢复库**（由失败模式生成）：`ReGrasp`（换抓取点/力）、`SwitchArm`（左/右/双臂）、`ChangePosture`（肘上/下、接近方向）、`PivotShift`（移动底盘/腰）、`ReLocalize`（重观测/重关联）、`MoveAside`（干扰物）、`RetreatAndRetry`（安全撤回）。每个恢复也是契约，必须过 `pre ∧ φ≥0`。
- **两击逃逸**：同一叶子的 `Retry` 失败两次，或 BT 根返回 Failure → `IP-49` 全局重规划（可调 LLM/GWM）；这保证 BT 不会在分布外场景里无限局部尝试。
- **chunk 截断**：正常在 chunk 边界 tick；若叶子 guard 在 chunk 中途触发（CBF/热/时延/前置失效），在下一个安全步截断 chunk，回到 BT tick；避免「执行完整个坏 chunk」。
- **fallback 排序学习**：离线用失败日志/扰动注入，在线用 bandit 更新每个 `(skill, failure_mode)` 的恢复顺序；只学排序，不学树结构，数据效率高。

**正确性论证**：
- **P51（计划保持）**：无 guard 失败时，tick 顺序 = π，chunk 数 = 计划步数；BT 不引入额外全局规划。
- **P52（无死锁/进度）**：每个 fallback 边绑定一个良基测度（剩余失败模式数/到目标距离/预算），且每次恢复必须改变状态或降级；有限失败下不会无限循环；根 Failure 上交全局规划。
- **P53（组合安全）**：每个叶子有 CBF/热/时延 guard；BT 组合采用 assume-guarantee：若每个叶子的局部不变式成立，则 Sequence/Fallback 的组合不变式成立；不依赖全局非线性证书。
- **P54（步数经济）**：失败率 p、局部恢复成本 c_rec 下，`E[N] ≤ N_plan + p/(1-p)c_rec`；当 `c_rec < c_global`（全局重规划含感知/LLM/重新定位），局部恢复更省步；两击逃逸限制最坏情况。
- **P55（与 IP-51 一致）**：叶子仅在 `φ≥0` 时执行；恢复也过同一可行性检查；因此 BT 不可能「选择一个臂做不到的技能」而不被发现。

**验证方法**：
- 离线：把 BT 抽象成有限谓词状态机，模型检查「无死锁/无未守护叶子/恢复可达」；对每个契约做前置/后置的单元测试。
- 在线：运行时监控 guard 违反率、fallback 触发率、两击逃逸率；把违反写入失败记忆；E76 做故障注入（对象移动/夹爪滑脱/遮挡/人为推/错误物体）。

### 3.4 IP-53 SKILL-GRAPH-INDUCTION（SGI，示范诱导技能图，完整设计）

**IP 卡片（六字段）**：
- **动机**：F68/F69 提供 32 任务约 32k 成功示范；v17 的 p_s、时长、姿态先验都是估计量；SGI 把它们变成数据统计。
- **与现有方案差异**：常规 VLA 直接把整段示范喂给大模型；SGI 显式挖出**技能段/转移/姿态/时长**，给 BT 提供结构先验，给 IP-49 提供 p_s，给 IP-51 提供姿态分布。它不是行为克隆替代，而是结构先验。
- **技术可行性**：变点检测（PELT/HMM）在 30fps 轨迹上毫秒级；特征=EE 速度/位移、夹爪开合、pivot/waist 变化、arm 使用；聚类 + DTW 对齐；每任务约 1000 条，离线可跑。
- **所需资源**：F68/F69 数据（公开）；算力=离线 CPU/GPU；无需人工标注（可用任务名/语言指令弱监督）。
- **落地步骤**：① 下载/流式读取 32 任务 LeRobot 数据；② 预处理 EE/夹爪/pivot；③ 变点分割+聚类；④ 建技能图/统计先验；⑤ 用 held-out 示范验证；⑥ 导出契约初始库与 BT 模板。
- **风险**：成功示范无失败标签→恢复仍靠扰动；分割粒度不稳→提供多粒度（任务级/阶段级/子技能级）；分布外→只用粗粒度转移图，精细状态交 IP-50。

**算法**：

```
for each task t, demo τ:
    x_t ← EE pose (base), g_t ← gripper, p_t ← pivot/waist
    features ← [Δx, ‖ẋ‖, Δg, Δp, arm_id]
    change_points ← PELT(features)            # 或 HMM 切换模型
    segments ← split(τ, change_points)
    for seg: extract (duration, displacement, gripper_event, arm_mode, q stats)
cluster segments across demos (DTW + 特征) → skill set S
build G_skill: nodes S, edges transition counts, task-conditioned
estimate p(s|t), p(s'|s), duration(s), p(q|s,goal), success(s) (from demo completion)
```

**输出**：技能契约初始库（pre/post 用任务名/阶段谓词弱标注）、BT 模板（每任务的主序列 + 常见 fallback）、p_s/时长先验、步数预算校准。

```python
# ===== 离线：SGI（IP-53）=====
def induce_skill_graph(task_datasets):

# ===== 离线：FK/IK + 姿态先验（IP-51）=====
def fit_arm_model(demos):
    theta = fit_fk([(q, x) for tau in demos for q, x in zip(tau.q, tau.ee)])
    posture = fit_posture_prior(demos)       # p(q | skill, goal)
    phi = fit_feasibility_proxy(theta, demos) # 可操作度/限位/自碰/力矩代理
    return theta, posture, phi

# ===== 运行期：BT 主循环（IP-52）=====
def act_v18(obs, state):
    ledger = update_ledger(...)               # IP-48
    sem = semantic_map.update(obs)            # IP-36
    if state.bt is None or sem.semantic_changed:
        plan = ip49.plan(sem.language, sem, priors, state.scenario, ledger)
        state.bt = ip52.compile(plan, skill_lib, sem, state.failure_memory, ledger)
    status, chunk = state.bt.tick(sem, ledger) # tick 在 chunk 边界
    if status == "FAIL":
        state.failure_memory.log(...)
        state.bt = None                        # 两击逃逸：全局重规划
        return safe_stop_or_replan(state)
    if chunk is None:
        return hold_position()
    # 叶子内：契约 → TO → CBF
    traj = ip50.refine(chunk, skill_contract=state.bt.current_contract, sem=sem)
    traj = ip33.cbf_filter(traj)               # 叶子级兜底
    return adapt(traj.next_chunk(ledger.T_a_eff), state.control_space)

# ===== 编译（简化）=====
def compile(plan, L, sem, M_f, budget):
    root = Seq(BudgetGuard(budget), ProgressGuard(sem.goal))
    for step in plan:
        variants = [C for C in L.variants(step) if C.pre(sem) and feasible(C, sem)]
        if not variants: return Fallback(GlobalReplan(step), PivotShift(step))
        leaf = Selector(sorted(variants, key=cost))
        rec  = Fallback(M_f.recoveries(step), generic_recoveries)
        root.add(Retry(GuardPost(step, Fallback(leaf, rec)), r=2))
    return flatten(root)
```

## 6. 清单迭代规则（继承 27–51 + 本轮新增 52–54）

- 继承规则 27–51（通道诚实/映射验证/SLO/fail-safe/灵感-现实校验/单模型合规/步骤分双解释/稠密监督/方法论遗产/元数据重照亮/语言口径分离/摊销/验证器分级/灵感词落地/层级联合规划/跨本体运动/流式韵律/渐进蒸馏/服务化/证书化/组合代数/热预算/期望得分/学习-TO/修剪优先）。
- **52（新增）：契约先行原则**——BT 的每个叶子必须是技能契约；执行前必须同时满足 `pre` 与 `φ≥0`；臂可行性是硬约束而非软惩罚；BT 不得直接输出未校验的关节目标。
- **53（新增）：行为树即执行层原则**——BT 由 E_score 计划编译而非手写；局部 fallback 优先，连续两次失败或根 Failure 必须上交全局规划；tick 是步数记账单位；chunk 截断由 guard 触发；只学 fallback 排序/变体选择，不对 BT 结构做端到端 RL。
- **54（新增）：数据先验诚实原则**——32 任务公开示范只做离线先验/辨识（技能图、FK/IK、姿态、时长、p_s），不进入测试时输入；必须显式标注「成功示范无失败标签」与「示范-评测分布差」；任何数据先验失败都要有 v17 回退路径。

**当前最值得押注**：**IP-52 EMBODIED-BEHAVIOR-TREE + IP-51 ARM-SKILL-CONTRACT 的组合**。它们是本轮唯一同时利用「32 任务公开示范 + 7-DoF 冗余 + BT 反应式恢复 + 官方 chunk/pivot 接口」的闭环，且可被 E74/E75 两个实验快速证实/证伪：先在离线示范上跑通技能分割与姿态可行性，再在仿真/真机上验证「局部恢复省步数」与「好姿态降自碰/奇异」；IP-49 仍可退化为 v17 规划器，IP-50 仍可退化为 VLA 伺服，BT/臂层是增量而非替代。

**本轮最大风险一句话**：技能契约与臂可行性模型都从成功示范归纳，若测试扰动落在示范支撑集之外，BT 会把「不可行/未见过」误判为「可恢复」，用局部 fallback 反复尝试而拒绝全局重规划，反而比 v17 更浪费步数与热预算；必须以 E73–E77 五重守门，并保留「同一叶子连续失败两次即上交全局规划器」的硬逃逸。
