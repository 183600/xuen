灵感驱动研究循环·新灵感轮第 1 轮；本轮灵感：「用户体验」×「容错控制」

> **基线**：第 3 轮产出 MetricVoiceGauge-NCD-HUTDH-v23 + IP-436–439（云边同步 CESC、少样本 FSVC、IP 认证 IPAM、四证一体 HPC-E+；其上承 v22 分层 PGEV/机械臂/深度感知，v21 语义-规范层，v20 联邦感知证书，v19/v17 各模块）。
> 本轮纪律：**安全不由"集合逐轮收缩"定义，而由"每个被执行动作都携带一条可机械复核的证明"定义**。不推倒 v23：CESC/FSVC/IPAM/HPC-E+ 全部保留。本轮只做一件事：**在 v23 之上加一层"可认证的可用性容错层"，用主动容错控制（FDI + 模式库重构）修复 v20–v23 累积的活性坍缩，用用户体验证书把"安全但不可用"升级为"安全且被正确信任"，并把安全不变量从"子集单调链"重新奠基为"证明守恒"**。

## 0. 直觉与动机

### 灵感 1（用户体验 → "安全但不可用"本身就是一种不安全）

直觉：前几轮把所有不确定性都兑换成"更保守"：多一层证书、多一次交集、多一个回退。代价是可行集越来越小、SafeStop 越来越频繁。用户看到的是：机器人频繁无故停顿、动作不可预测、拒绝时不给理由。**更危险的连锁反应是：一个频繁误停、无法解释的安全系统会被操作员绕过**——于是"过度保守"经由信任崩塌，反向变成"不安全"。所以用户体验不是安全之上的软装饰，而是**对退化策略的硬约束**：系统不仅要安全，还要**被正确地信任**（既不过度信任，也不因误停而失去信任）。

严谨定义：**用户体验证书 (UXC)** 为一个可测、可审计的六元组
`UXC = (φ_f, L, E, PS, τ_resp, τ_rec)`，其中 φ_f 为每小时间**不必要**干预次数（fluency 的反向指标），L 为运动可读性/可预测性，E 为每次拒证/停机**附带可机械复核理由**的比例（explainability），PS 为感知安全度，τ_resp 为响应延迟，τ_rec 为故障后恢复时间。**信任校准误差** `TC = |reliance − true_reliability|`：操作员实际依赖率与系统真实可靠率之差。目标不是最大化依赖，而是 `TC ≤ ε_tc`。

核心创新：**可用性非扩张选择器 `Sel_ux`**——它只在**已经安全**的计划集上做排序与选择，绝不扩张安全集；活性提升来自"减少不必要的保守"（更精确的故障隔离）与"更快恢复"（τ_rec 下降），而非放宽安全边界。反直觉点：**UX 的活性预算与安全集正交——优化 UX 的变量里不出现任何安全阈值**。

### 灵感 2（容错控制 → 从"被动全局回退"到"主动可诊断重构"）

直觉：v23 的退化链 `Exec_v23 ⊆ Exec_v22 ⊆ ...` 是**被动容错 (passive FTC)**：任一层失效就整体回退到全局最保守模式，扔掉大量仍然安全可用的能力。控制理论给出另一半：**主动容错 (active FTC)** = 故障检测与隔离 (FDI) + 控制重构 (reconfiguration)。精确知道"哪个部件坏了"，就能切到**预先认证的模式库**里仍保证安全的模式，而不是一刀切停摆；故障清除后再沿**带滞回的恢复路径**回到名义模式。

严谨定义：故障集 `F = {f_s 传感, f_a 执行, f_c 通信, f_p 感知, f_k 计算}`；残差 `r(t) = y(t) − ŷ(t)`，阈值 `J_th`；诊断 `d(t) ∈ F ∪ {∅}`，可信度 `conf(d)`；**可诊断性**：故障 f 在 `T_d` 内可隔离，若 `|r(t)| > J_th` 在 `[t_f, t_f+T_d]` 内成立。模式库 `M = {m_0, …, m_K}`，每模式携带
`ModeCert(m) = (I_m, R_m, Rec_m, Proof_m)`：不变式、认证可达集、恢复条件、以及**指向 v23 名义证书的证明引用**。重构监督器 `σ(t) ∈ M`，带驻留时间 `τ_dwell` 与滞回带 `h`。

反直觉点：**主动重构允许在故障下把可行集"重新变大"**（相对 v23 的粗粒度全局回退），但这**不是放宽安全**——因为每个 `R_m` 都独立持有安全证明，且故障只减能力，故 `R_m ⊆ Safe(f_m) ⊆ Safe_v23(∅)`（`Safe_v23(∅)` 为名义安全集）。也就是说：**安全按"证明"守恒，而不是按"集合单调收缩"守恒**；子集单调只是证明守恒的一个充分特例。

### 两者如何统一

统一为 **可认证的可用性容错层 (Certified Usable Fault-Tolerant Layer, CUFT)**：FTC 回答"故障下还能安全做什么、如何精确切换与恢复"，UX 回答"在仍安全的动作里选哪个、如何让人理解与正确信任"。统一不变量：**每个被执行动作都携带一条归属于名义安全集 `Safe_v23(∅)` 的、可机械复核的证明**。执行集
`Exec_v24(t) = Sel_ux( Safe_v23(∅) ∩ R_{σ(t)} ) ⊆ Safe_v23(∅)`。

这把 v20–v23 的"子集链"重新奠基为"**证明链**"：子集单调是证明链的充分特例；当需要在故障下恢复活性时，我们用"逐模式证明 + FDI 可靠性"替代"全局最保守子集"，在不牺牲**名义安全**的前提下修复活性坍缩。统一准入门 **HPC-UX = (HPC-E+ 证书 ∧ 当前模式 ModeCert ∧ UXC 解释)**。注意：本轮**有意**放宽 `Exec_v24 ⊆ Exec_v23_fallback`（v23 故障时的粗回退），因为那条粗回退本身过度保守；真正必须守恒的是 `Exec_v24 ⊆ Safe_v23(∅)`，它由证明链保证。这一"放宽"是否可接受，完全押在 FDI 诊断的正确性上——这正是本轮最大风险。

## 1. 研究问题（轮次升级版）

- **Q1（UX 的形式化与信任）**：如何把 φ_f/L/E/PS/τ_resp/τ_rec 变成可审计证书？如何把"不过度保守"形式化为 `Sel_ux` 的排序目标而不触碰安全阈值？信任校准误差 `TC` 如何在部署中在线估计（reliance 是否可观测、如何避免用系统自身输出当标签）？

- **Q2（FDI 的可诊断性与误诊界）**：残差如何生成并保证故障在 T_d 内隔离？在冗余不足（单模态）时，可诊断性如何退化、误诊率 `P(misdiag)` 的上界如何标定？假阴性（漏诊）与假阳性（误报）如何区别对待（漏诊危险、误报只损失活性）？

- **Q3（重构的安全性与无抖振）**：如何预认证模式库使 `R_m ⊆ Safe(f_m)` 且 `Safe(f_m) ⊆ Safe_v23(∅)`？驻留时间 τ_dwell 与滞回 h 如何保证切换不产生 Zeno 抖振？故障清除后的恢复路径如何保证逐步回到名义集而非一步跳回？

- **Q4（UX 与 FTC 的耦合）**：解释证书如何与**当前诊断**绑定，避免"用一个错误故障假设去解释一次错误重构"？UX 的活性压力如何不诱导 FDI 阈值被放松（安全参数与体验参数硬隔离）？τ_rec 与 τ_dwell、v23 的 APS 新鲜度阶梯如何叠加？

## 2. 设计原则（在 P37–P42 基础上新增 P43–P45）

**P43 证明守恒律（Proof Preservation）**
任何被执行动作 π 必须携带一条归属于名义安全集的证明 `⊢_v23 π`（即 π ∈ Safe_v23(∅)）。FTC 的模式库与 UX 的选择器只能在**带证明**的动作上操作：
`Exec_v24(t) = Sel_ux( Safe_v23(∅) ∩ R_{σ(t)} ) ⊆ Safe_v23(∅)`。
子集链 `⊆` 是证明守恒的充分非必要条件；本律是 v20–v23 单调链的严格推广。

**P44 可诊断重构律（Diagnosable Reconfiguration）**
模式切换仅当 `conf(d(t)) ≥ θ_diag` 且持续 `≥ τ_dwell` 时发生，带滞回 `h`；无诊断 → 保持当前模式或退最保守。误诊概率上界 `P(misdiag) ≤ ε_fdi`，且**漏诊与误报非对称**：漏诊（假阴性）走二次确认 + 人机共确认，误报（假阳性）只损失活性。每个 `R_m ⊆ Safe(f_m)`，故障只减能力故 `Safe(f_m) ⊆ Safe_v23(∅)`。

**P45 可用性非扩张律（Usability Non-Expansion）**
`Sel_ux` 的定义域与值域都 ⊆ 当前安全集，其优化变量中**不出现任何安全阈值**（安全参数与体验参数硬隔离）。每条解释必须引用**当前诊断 `d(t)`** 与对应 `ModeCert`；当 `conf(d) < θ_diag` 时，解释必须显式声明"诊断不确定"，禁止给出确定性口吻的解释。信任校准目标 `TC ≤ ε_tc`，既惩罚过度信任也惩罚信任不足。

## 3. 与基线的接口（如何退化）

- **FDI 失效（无法诊断）** ⇒ 退化为 v23 被动全局回退 ⇒ `Exec ⊆ Safe_v23(∅)` 仍成立（证明守恒不依赖 FDI）；
- **模式库某模式证明失效** ⇒ 禁用该模式（从 M 删除）⇒ 可行集只减；
- **UX 失效** ⇒ `Sel_ux` 退化为 v23 默认选择（最保守/最短路径）⇒ 安全不变，仅体验变差；
- **解释失效** ⇒ 拒证仍发生但无解释 ⇒ 安全不变，但信任风险上升 ⇒ 触发保守（降低自动化等级）；
- **诊断误报** ⇒ 不必要的降级 ⇒ 活性损失，安全不变；
- **诊断漏诊** ⇒ **本轮最大风险**：在错误故障假设下重构回更大可行集 ⇒ 需二次确认 + 模式证明的最坏情形回退；
- **全部失效** ⇒ 完全回退 v23。
- **安全继承的重新表述**：`Exec_v24(t) ⊆ Safe_v23(∅)` 恒成立；相对 v23 的**故障回退**可能变大（有意为之），但相对**名义安全集**永不越界。

## 4. 预期贡献

1. **用户体验证书化**：把 fluency/legibility/explainability/perceived safety/延迟/恢复时间变成可审计证书，并把"信任校准误差"引入安全系统目标；
2. **主动可诊断容错**：五类故障的 FDI + 预认证模式库 + 带滞回恢复，把"被动全局回退"升级为"精确模式重构"；
3. **范式升级：从子集单调链到证明守恒**：解释并修复 v20–v23 的活性坍缩——安全由"每条动作带证明"守恒，子集链成为其特例；
4. **可解释的安全**：解释与诊断绑定，诊断不确定时显式声明，避免"用错误假设解释错误动作"；
5. **统一 HPC-UX 门**：HPC-E+ ∪ ModeCert ∪ UXC，`Exec_v24 ⊆ Safe_v23(∅)` 闭环。

## 5. 本轮最大风险

**一句话**：主动容错把安全从"集合单调收缩"换成"逐模式证明 + FDI 可靠性"，一旦 FDI 系统性**漏诊**（真实故障未被隔离，系统却在名义/错误假设下把可行集重构得更大），机器人会在**用户因体验改善而更信任**的同时，把动作扩张进一个"证明挂在错误故障假设上"的区域——即"可信的误诊"。

## 1. 关键算法骨架

```python
# ============================================================
# IP-440 Fault Diagnosis Module (FTDM) — 故障检测与隔离
# ============================================================
class FaultType(Enum):
    SENSOR = "f_s"; ACTUATOR = "f_a"; COMM = "f_c"
    PERCEPTION = "f_p"; COMPUTE = "f_k"

@dataclass
class Diagnosis:
    fault: Optional[FaultType]
    confidence: float          # conf(d)
    residual_norm: float
    t_detected: float

class FaultDiagnosisModule:
    def __init__(self, J_th: float, T_d: float, signature: dict,
                 epsilon_fn: float = 1e-4, epsilon_fp: float = 1e-2,
                 confirm_n: int = 2):
        self.J_th = J_th
        self.T_d = T_d
        self.signature = signature      # 故障 -> 残差方向签名（可隔离性）
        self.epsilon_fn, self.epsilon_fp = epsilon_fn, epsilon_fp
        self.confirm_n = confirm_n      # 漏诊侧需要的连续确认次数
        self._hits: dict[FaultType, int] = defaultdict(int)

    def residual(self, y, y_hat):
        return np.asarray(y) - np.asarray(y_hat)

    def update(self, t: float, y, y_hat) -> Diagnosis:
        r = self.residual(y, y_hat)
        norm = float(np.linalg.norm(r))
        if norm <= self.J_th:
            self._hits.clear()          # 回到名义带
            return Diagnosis(None, 1.0, norm, t)

        # 基于残差方向做隔离（最近签名匹配）
        cand = max(self.signature,
                   key=lambda f: float(np.dot(r, self.signature[f])))
        conf = self._signature_confidence(r, cand)
        self._hits[cand] += 1

        # 非对称确认：漏诊危险 → 需连续 confirm_n 次；不确定则降 conf
        if self._hits[cand] < self.confirm_n:
            return Diagnosis(cand, conf * 0.5, norm, t)   # 未确认，低置信
        return Diagnosis(cand, conf, norm, t)

    def _signature_confidence(self, r, f) -> float:
        # 归一化投影：方向一致度
        denom = np.linalg.norm(r) * np.linalg.norm(self.signature[f]) + 1e-9
        return float(np.clip(np.dot(r, self.signature[f]) / denom, 0.0, 1.0))

    def diagnosable(self, t_since_fault: float) -> bool:
        return t_since_fault <= self.T_d


# ============================================================
# IP-441 Certified Control Mode Bank (CCMB) — 预认证模式库
# ============================================================
@dataclass
class ModeCert:
    mode_id: int
    fault_hypothesis: Optional[FaultType]   # None = 名义
    invariant: Callable[[Any], bool]        # I_m
    reachable_set: frozenset                # R_m ⊆ Safe(f_m)
    recovery_condition: Callable[[Any], bool]  # Rec_m
    proof_ref: str                          # 指向 v23 名义证书的引用
    enabled: bool = True

    def certifies(self, plan) -> bool:
        return self.enabled and plan in self.reachable_set

class ControlModeBank:
    def __init__(self, safe_v23: frozenset):
        self.safe_v23 = safe_v23            # Safe_v23(∅) 锚点
        self.modes: dict[int, ModeCert] = {}

    def register(self, cert: ModeCert):
        # 预认证硬约束：模式认证集必须 ⊆ 名义安全集（证明守恒）
        if not cert.reachable_set.issubset(self.safe_v23):
            raise ValueError(f"mode {cert.mode_id} exceeds Safe_v23(∅)")
        self.modes[cert.mode_id] = cert

    def nominal(self) -> ModeCert:
        return self.modes[0]

    def for_fault(self, f: FaultType) -> Optional[ModeCert]:
        for m in self.modes.values():
            if m.enabled and m.fault_hypothesis == f:
                return m
        return None

    def disable(self, mode_id: int):
        self.modes[mode_id].enabled = False   # 证明失效 ⇒ 只减可行集


# ============================================================
# IP-442 Reconfiguration Supervisor (RCS) — 带滞回的重构监督器
# ============================================================
class ReconfigurationSupervisor:
    def __init__(self, bank: ControlModeBank, tau_dwell: float,
                 h: float, theta_diag: float = 0.9):
        self.bank = bank
        self.tau_dwell = tau_dwell
        self.h = h                       # 滞回带
        self.theta_diag = theta_diag
        self.active: ModeCert = bank.nominal()
        self._last_switch_t = -1e9
        self._pending: Optional[ModeCert] = None
        self._pending_since = 0.0

    def step(self, t: float, diag: Diagnosis) -> ModeCert:
        target = self._target(diag)
        # 驻留时间约束（防抖）
        if t - self._last_switch_t < self.tau_dwell:
            return self.active
        if target is None or target.mode_id == self.active.mode_id:
            self._pending = None
            return self.active
        # 稳定性确认：目标需持续存在（隐式由 tau_dwell 保证）
        # 滞回：只有"改善"超过 h 才切（此处以安全集大小差为代理）
        gain = len(target.reachable_set) - len(self.active.reachable_set)
        if target.mode_id != self.bank.nominal().mode_id and gain < -self.h:
            return self.active          # 无足够改善，保持（避免抖振）
        self.active = target
        self._last_switch_t = t
        return self.active

    def _target(self, diag: Diagnosis) -> Optional[ModeCert]:
        if diag.fault is None:
            return self.bank.nominal()          # 故障清除 → 恢复路径回名义
        if diag.confidence < self.theta_diag:
            return self.active                  # 诊断不确定 → 保持/保守
        return self.bank.for_fault(diag.fault) or self.bank.nominal()

    def recovery_ok(self, state) -> bool:
        return self.active.recovery_condition(state)


# ============================================================
# IP-443 User Experience Certificate (UXC) + 非扩张选择器
# ============================================================
@dataclass
class UXCertificate:
    fluency_stops_per_hour: float     # φ_f
    legibility: float                 # L
    explainability: float             # E
    perceived_safety: float           # PS
    response_latency: float           # τ_resp
    recovery_time: float              # τ_rec
    trust_calibration_error: float    # TC

    def valid(self, eps_tc: float) -> bool:
        return (self.fluency_stops_per_hour <= 2.0
                and self.legibility >= 0.8
                and self.explainability >= 0.99
                and self.response_latency <= 0.05
                and self.recovery_time <= 2.0
                and self.trust_calibration_error <= eps_tc)

class UXSelector:
    """只在安全集内排序；目标函数中不含任何安全阈值（P45）。"""
    def __init__(self, weights: dict, eps_tc: float = 0.1):
        self.w = weights
        self.eps_tc = eps_tc

    def select(self, safe_plans):
        if not safe_plans:
            return None
        return max(safe_plans, key=self._score)

    def _score(self, plan) -> float:
        # 纯体验项：路径平滑度/可读性/预估停顿；无 margin/安全参数
        return (self.w["legibility"] * plan.legibility
                - self.w["stops"] * plan.expected_stops
                - self.w["latency"] * plan.expected_latency)


# ============================================================
# IP-444 Explanation & Trust Calibration Module (ETCM)
# ============================================================
class ExplanationTrustModule:
    def __init__(self, eps_tc: float = 0.1, theta_diag: float = 0.9):
        self.eps_tc = eps_tc
        self.theta_diag = theta_diag
        self.TC = 0.0

    def explain(self, decision, diag: Diagnosis, mode: ModeCert) -> dict:
        # 解释必须绑定当前诊断；诊断不确定时显式声明（P45）
        if diag.confidence < self.theta_diag:
            return {
                "text": "诊断不确定，采取保守动作",
                "certainty": "low",
                "diagnosis": diag.fault.value if diag.fault else "unknown",
                "mode": mode.mode_id,
                "proof_ref": mode.proof_ref,
            }
        if decision.admitted:
            return {
                "text": f"执行计划 {decision.plan_id}",
                "certainty": "high",
                "diagnosis": diag.fault.value if diag.fault else "nominal",
                "mode": mode.mode_id,
                "proof_ref": mode.proof_ref,
            }
        return {
            "text": f"拒证：{decision.reason}",
            "certainty": "high",
            "diagnosis": diag.fault.value if diag.fault else "nominal",
            "mode": mode.mode_id,
            "proof_ref": mode.proof_ref,
        }

    def update_trust(self, reliance: float, true_reliability: float) -> str:
        self.TC = abs(reliance - true_reliability)
        if self.TC > self.eps_tc:
            # 过度信任或信任不足 → 降低自动化等级 / 请求确认
            return "reduce_automation_level" if reliance > true_reliability else "request_confirmation"
        return "ok"


# ============================================================
# IP-445 HPC-UX 统一准入门
# ============================================================
@dataclass
class HPCUXGate:
    hpc_e_plus: 'HPCEPlus'
    bank: ControlModeBank
    rcs: ReconfigurationSupervisor
    ux: UXSelector
    etcm: ExplanationTrustModule

    def admits(self, plan, mode: ModeCert, diag: Diagnosis, state) -> tuple[bool, dict]:
        # 1. v23 四证一体（含 Safe_v23(∅) 证明）
        if not self.hpc_e_plus.admits(
                plan, state.x, state.v, state.z,
                state.E_res, state.margin_req, state.modules):
            return False, self.etcm.explain(_Denied("hpc_e_plus"), diag, mode)

        # 2. 模式证书：R_{σ} 且 ⊆ Safe_v23(∅)（P43 证明守恒）
        if not self.bank.certifies(mode, plan):
            return False, self.etcm.explain(_Denied("mode_cert"), diag, mode)

        # 3. UX 仅在安全集内选择（P45）
        chosen = self.ux.select([plan])
        expl = self.etcm.explain(_Admitted(chosen), diag, mode)
        return True, expl


# ============================================================
# 端到端流水线（在 v23 流水线上插入 CUFT 层）
# ============================================================
class CertifiedUsableFTPipeline:
    def __init__(self, config: dict):
        self.v23 = PerceptionComplianceEnergyPipeline(config)   # 复用 v23
        self.ftdm = FaultDiagnosisModule(config["J_th"], config["T_d"],
                                         config["signature"])
        self.bank = ControlModeBank(config["safe_v23"])
        self.rcs = ReconfigurationSupervisor(self.bank, config["tau_dwell"], config["h"])
        self.ux = UXSelector(config["ux_weights"], config["eps_tc"])
        self.etcm = ExplanationTrustModule(config["eps_tc"])
        self.gate = HPCUXGate(self.v23.hpc_e_plus, self.bank, self.rcs,
                              self.ux, self.etcm)

    def step(self, t, sensor_data, y, y_hat, reliance, reliability):
        diag = self.ftdm.update(t, y, y_hat)           # 1. FDI
        mode = self.rcs.step(t, diag)                  # 2. 重构
        if not self.ftdm.diagnosable(t - diag.t_detected):
            mode = self.bank.nominal()                 # 不可诊断 → 保守
        _, info = self.v23.step(sensor_data)           # 3. v23 证书链
        admitted, expl = self.gate.admits(info.get("plan"), mode, diag,
                                          _state_from(sensor_data))
        trust = self.etcm.update_trust(reliance, reliability)  # 4. 信任校准
        return admitted, {"mode": mode.mode_id, "diag": diag,
                          "explanation": expl, "trust": trust}
```

## 2. 复杂度分析

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 |
|---|---|---|---|
| FTDM 残差/隔离 | O(\|r\|·\|F\|) 每步 | O(\|F\|) | \|F\|=5, T_d, J_th |
| CCMB 模式查询 | O(\|M\|) 或 O(1) 哈希 | O(\|M\|·\|R\|) | \|M\|≤8, \|R\|≈10³ |
| RCS 切换判定 | O(1) | O(1) | τ_dwell, h |
| UXC 选择 | O(\|S\|·d_plan) | O(\|S\|) | \|S\| 安全计划数 |
| ETCM 解释/信任 | O(1) | O(1) | θ_diag, ε_tc |
| HPC-UX 准入 | O(v23 准入 + \|M\|) | O(1) 增量 | 与 v23 同阶 |
| 端到端单步 | O(\|det\|·d + \|r\|·\|F\| + \|S\|) | O(\|D_calib\|+\|Proto\|) | 50Hz, <20ms |

**实时性保证**：CUFT 层新增关键路径（FTDM.update + RCS.step + UXC.select）均为 O(\|F\|) / O(1) / O(\|S\|) 级，无阻塞 I/O；FDI 残差与 v23 证书链共享同一传感器帧，不引入额外同步开销，满足 50Hz 控制环。

## 3. 正确性论证

### 引理 1（证明守恒 ⇒ 名义安全）
**陈述**：若每个被执行动作 π ∈ Exec_v24(t) 满足 `⊢_v23 π`（π ∈ Safe_v23(∅)），则对任意 t，`Exec_v24(t) ⊆ Safe_v23(∅)`，v24 不引入任何 v23 名义意义上的新不安全动作。

**证明**：
1. `Exec_v24(t) = Sel_ux(Safe_v23(∅) ∩ R_{σ(t)})`。
2. `Sel_ux` 值域 ⊆ 定义域（P45），故 `Sel_ux(S) ⊆ S ⊆ Safe_v23(∅)`。
3. 与 σ(t)、d(t) 无关，恒成立。∎

### 引理 2（故障单调性：故障只减能力）
**陈述**：对任意故障 f ∈ F，`Safe(f) ⊆ Safe_v23(∅)`。

**证明**：传感/通信/计算故障只减少可用信息，感知故障只降低证据质量，执行故障只减少可控自由度；在"信息与能力减少不会使原本不安全动作变安全"的标准假设下，v23 各证书层在故障时只会更保守（交集更多、误差界更大），故安全集单调收缩。∎
**推论**：`R_m ⊆ Safe(f_m) ⊆ Safe_v23(∅)`，即引理 1 对每个模式成立。

### 引理 3（可诊断重构的误诊风险界）
**陈述**：设诊断器漏诊率 `P(d=∅ | f≠∅) ≤ ε_fn`、误报率 `P(d≠∅ | f=∅) ≤ ε_fp`，则每次重构进入"错误故障假设"的概率 ≤ ε_fn；在错误假设下执行的最坏后果被 `Exec_v24 ⊆ Safe_v23(∅)` 界定，但**可能违反 Safe(f)**（f 为真实故障）。

**证明**：
1. 当真实故障 f 存在而诊断漏报（概率 ≤ ε_fn），RCS 按 `_target` 回到名义或错误模式 m'，其 R_{m'} 仅对 f' 认证。
2. 由引理 1/2，R_{m'} ⊆ Safe_v23(∅)，故不越名义安全；但 `R_{m'} ⊄ Safe(f)` 可能成立，故存在真实故障下的不安全动作。
3. 误报（≤ ε_fp）只触发不必要的保守模式，`R ⊆ Safe_v23(∅)`，仅损活性。∎
**注**：此引理明确把"故障下的安全"条件化在 FDI 正确性上——这是 P43 证明链的代价，也是本轮最大风险的形式来源。

### 引理 4（驻留 + 滞回 ⇒ 无 Zeno 抖振）
**陈述**：若 `τ_dwell ≥ 2·τ_resp` 且滞回 `h ≥ 2·σ_r`（σ_r 为残差噪声带宽），则 RCS 的切换序列在任意有限时间窗内切换次数有限，不产生 Zeno 抖振。

**证明**：驻留时间强制相邻切换间隔 ≥ τ_dwell > 0；滞回带使阈值附近的目标在未超过 h 前不触发切换，抑制残差噪声引起的反复越阈；两者共同保证切换事件的时间间隔有正下界。∎

### 定理（HPC-UX 门的名义安全-可用性-容错性）
**陈述**：`HPCUXGate.admits(π) = True` ⟺ π 同时满足 (1) v23 四证一体；(2) 当前模式证书 `ModeCert(σ)` 认证；(3) 由 `Sel_ux` 在安全集内选出并附诊断绑定的解释。当 FDI 诊断正确时，v24 在故障下安全且可用性不劣于 v23 的粗回退；当诊断漏诊（≤ ε_fn）时，安全性仍不越 `Safe_v23(∅)`，但可能违反真实故障安全集 `Safe(f)`。

**证明**：直接由 `admits` 的连言条件与引理 1–4 可得。必要性：任一条件缺失即拒证。充分性：诊断正确 ⇒ 模式 m 对应真实 f ⇒ `R_m ⊆ Safe(f)`（引理 2 推论）∧ 引理 1 保名义安全 ∧ 引理 4 保切换稳定；诊断漏诊 ⇒ 引理 3 给出风险界。∎

## 4. 已知风险与缓解

| 编号 | 描述 | 严重度 | 缓解措施 | 剩余风险 |
|---|---|---|---|---|
| R1 | FDI 漏诊 → 在错误故障假设下重构回更大可行集（"可信的误诊"） | 最高 | 1) 漏诊侧连续 confirm_n 次确认；2) 诊断不确定（conf<θ_diag）时不扩张、保持保守；3) 二次独立 FDI 通道交叉验证；4) 人机共确认用于高风险扩张 | 系统性漏诊（如多故障并发、故障被误识别为另一类）仍可能绕过 |
| R2 | 模式频繁切换/抖振 | 中 | τ_dwell ≥ 2τ_resp；滞回 h ≥ 2σ_r；切换需"改善量 > h" | 强非平稳扰动下驻留时间可能拖慢必要降级 |
| R3 | UX 活性压力诱导安全阈值被"软"放松 | 高 | P45 硬隔离：`Sel_ux` 优化变量不含任何安全参数；UXC 只读安全集 | 组织层面 KPI 压力仍可能要求改安全参数（需流程约束） |
| R4 | 解释错误 / 误导信任（用错误诊断解释错误重构） | 高 | 解释强制绑定当前诊断与 ModeCert；conf<θ_diag 时显式声明"诊断不确定"；TC 超限降自动化等级 | reliance 在线难观测，TC 估计本身有误差 |
| R5 | 模式库证明与真实故障模型不符（预认证时假设的 f_m ≠ 实际 f） | 高 | 故障注入测试覆盖每类 f；模式注册时强制 `R_m ⊆ Safe(f_m)` 复核；证明引用 v23 名义证书可机械重放 | 未枚举的复合故障（f_s∧f_a 同时）可能落在所有模式证明之外 |

## 6. 本轮最大风险（最终确认）

**一句话**：主动容错把安全从"集合单调收缩"换成"逐模式证明 + FDI 可靠性"，一旦 FDI 系统性**漏诊**（真实故障未被隔离，系统却在名义/错误假设下把可行集重构得更大），机器人会在**用户因体验改善而更信任**的同时，把动作扩张进一个"证明挂在错误故障假设上"的区域——即"可信的误诊"。
