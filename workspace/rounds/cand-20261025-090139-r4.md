# 第 8 轮（本次循环第 4 轮）· GRASP：抓取是闸门，双臂是稳定器，快速原型是迭代器

> 检索/复核日期：2026-10-25（UTC）。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「快速原型」「情感语音」「双臂协调」。我先给上一轮一个直接纠正：**把 8.6pp 的“步骤分-成功率差”读成“大部分失败倒在最后一步”是反的**；同一批占位基线数据重算后，失败主要发生在第一抓/第一段搬运。于是本轮把主战场从“终局放置”移到“第一抓”，把双臂从“双手任务”改造成“第一抓的稳定器/验证器”，把快速原型改造成“一天一轮的第一抓变体锻造”，把情感语音剪枝为“人类干预动作效价”的低成本恢复插件。终局放置保留为“最后一公里”，不再是主闸门。

## 0. 先纠正上一轮的方向性错误

### 0.1 8.6pp 不是“倒在最后一步”，而是“很早就倒了”

设任务成功率 p、平均步骤分 q（均为 0–100）。失败者平均拿到的部分分：

```text
A = (q - p) / (100 - p) × 100
```

用占位榜 8 模型 × 32 任务的均值：p≈25.2，q≈33.8，A≈11.5 分。32 个任务的第一步平均权重 w1≈35.5 分（中位数 30，范围 20–50）。也就是说，**即便把所有部分分都算给第一步，最多也只有约 A/w1≈32% 的失败者完成了第一步**；第一步成功率上界约 p+(1-p)×0.32≈49%，真实值很可能更低。

反过来，如果失败真的集中在终局，失败者应该拿到“终局之前的所有分”。终局权重 wn 平均约 39.8 分；若所有失败都发生在终局，步骤分应为：

```text
q_terminal = p + (1-p) × (100 - wn) / 100
```

对 32 个任务，q_terminal 约 61–85 分；实际 q 只有 24–41 分。把实际 gap 与“全终局失败”gap 相比，**终局最多解释约 20% 的丢分，约 80% 的丢分发生在终局之前**。

结论：终局放置是“乘数”，不是“闸门”。上一轮 PILOT 的终局模块仍然有用，但它是“最后一公里”；主闸门是第一抓/第一段搬运。

> 证据边界：以上假设 `score_steps` 是累计计分（info.json 的 32 个任务分值都加总到 100，手册称“步骤分”，这是最自然的读法）。若官方实际按“达到的最高步骤”或“每步独立成功率”计分，A 的解释会变；必须在调试槽用逐步日志校准。占位榜本身是 `gen_leaderboard.py` 生成、详情页视频为占位，不能当真实排名，只能当结构先验。

### 0.2 这个纠正改变预算分配

上一轮把约 40% 预算给终局放置。按上面的算术，终局条件成功 +5pp 只带来约 +1.5pp 总分（因为到达终局的比例低）；第一抓 +10pp 在“下游条件成功率 0.5–0.7”的假设下带来 +5–7pp。**第一抓的边际收益是终局的 3–4 倍**。本轮预算改为：第一抓 40%、双臂稳定 20%、快速原型 20%、恢复/干预 10%、部署 10%。

## 1. 三个灵感词，各自钉到官方事实

### 1.1 快速原型：不是“造全孪生”，是“一天一轮的第一抓变体锻造”

官方数据已经给了最好的原型材料：32 任务、32,000 条演示、169 小时、四路 640×480@30fps、EE 位姿有 base/torso 两套、每任务 5 条英文复述（共 160 条）。第一抓的变体不需要高保真布料/流体/透明物理，只需要：

- 物体位姿 ±2–5cm、±15–30° yaw；
- 桌面加 1–3 个干扰物（从其他任务借）；
- 背景/光照替换（从其他演示借）；
- 容器位姿平移；
- 人手从不同方向进入（遮挡/干预）。

用 2.5D 分层 + 分割/修复 + 运动学碰撞检查，一天可以为一个任务批生成 100–300 个第一抓变体，回放 5–10 条演示的第一段，输出“失败卡”（变体、失败模式、疑似原因、建议数据）。这不是全孪生，也不是通用数据增强；它只服务第一抓，所以便宜、快、可每天迭代。ASPIRE 的 code-as-policy 技能库、Recova 的数字孪生恢复、Kintsugi 的失败回放都说明：**失败样本和快速分支比“更大多模态预训练”更接近边际收益**。

### 1.2 双臂协调：不是“双手任务”，是“第一抓的稳定器/验证器”

我把 32 个数据集的 `meta/episodes` 全量下载，解析左右 EE 位姿与夹爪 std：

- 29/32 任务 `frac_both_move≈1.00`，即双臂都在动；23/32 任务双手夹爪中位 std 都 >0.8（严格双臂）；27/32 双手都 >0.5。
- 真正“单手”的只有 5 个：HangCup（左夹爪 std 0.00/右 1.93）、PickOutBattery（0.00/1.46）、SpellRobot（0.17/1.38）、FruitSorting（0.49/0.59）、ConveyorSorting（0.61/0.33）。
- 任务级平均成功率：严格双臂（23）25.0% vs 非严格（9）25.6%，宽松双臂（27）25.2% vs 单手（5）24.8%，两种分法差异都 <1pp；`bothmed` 与成功率的相关系数仅约 +0.32，`right_dom_move` 约 -0.28。**“任务是不是双臂”不是难度驱动**。
- 模型级（严格 23 vs 非严格 9）：只有 DreamZero（-2.6pp）和 GigaBrain-0（-2.3pp）超过 2pp；DM0（-1.6）/PI（-1.1）小幅为负，Spirit（+1.6）/MolmoAct2（+0.7）/WALL（+0.3）小幅为正，GR00T（-0.1）持平。上一轮“MolmoAct2 -3.8 最大”在当前两种分法下都无法复现，标注为阈值依赖，不能作为本轮前提。

那机会在哪？在**名义单手任务里，第二臂其实也在动，但没有被当成稳定器用**。HangCup 左夹爪从不闭合，左臂却全程运动；PickOutBattery 左夹爪 0.00，左臂也在动；SpellRobot 左夹爪 0.17。演示是双臂遥操作，任务却只需要一只手——这正是“把第二臂从‘跟着动’升级为‘主动稳住/验证’”的空间。

具体做法：从演示里给每帧标 `manipulator / stabilizer / idle / recovery` 角色；在动作专家上加角色 token、跨臂相对位姿 token、SSG 相位 token；第一抓闭合前让对侧臂去稳定容器/物体底座，闭合后用腕部相机验证接触/滑移，不确定就重抓。这不是 BiCICLe 的 leader-follower 双操作手，也不是 MA-VLA 的多臂原子动作分配；它只把第二臂当**第一抓的稳定器/验证器**，单模型、不改 backbone。

### 1.3 情感语音：没有音频通道，剪枝；只保留“干预动作效价”

官方观测是四路 RGB + 双臂状态 + 夹爪 + 下半身 + 一个 episode 内不变的 `observation.language` 字符串，**没有音频**；评测语言是固定的 5 条复述之一。TTS、韵律、情感识别都没有输入通道，直接剪掉，不投。

可迁移的残余有两个：

1. **人类干预的动作“韵律/效价”**：human 轴每任务 2/10 次，官方 `human_1_note`/`human_4_note` 给了剧本，绝大多数是“一次 1-DOF 平移”或“完成后撤销”。人的动作速度、方向、平滑度、是否把物体带走，等价于一种非语音的“情感/意图”信号：`undo`（慢、反向）、`displace`（快、横向）、`remove`（带走）、`add`（放入新物体）、`occlude`（手挡相机）。分类后选恢复策略：undo→回退相位；displace→重定位；remove→重规划剩余物体；add→更新场景图；occlude→等待/后退。这比“把所有干预当同一种异常”更省尝试。
2. **策略自身的“置信度/紧迫感”**：第一抓闭合后，用腕部图像 + 动作熵估计“抓稳了吗”；低置信就重抓（UTRG），而不是硬着头皮搬运。这是把“情感”当作内部置信信号，归入 FGS 的验证器，不单列成一个新模块。

这两项都是低成本插件，合计不超过 10% 预算；它们不改变“第一抓是主闸门”的判断。

## 2. 本轮主判断：GRASP-GPR

**G**ate-aware failure attribution（FSP）：用公开 `score_steps` + 成功率/步骤分反推失败阶段，先打最早的高损失步骤，而不是静态权重最大的终局。
**R**ole-aware bimanual stabilization（FGS）：第二臂在第一抓/第一段搬运中做稳定器 + 腕部验证器；角色 token + 跨臂相对位姿 + 相位时钟 + 对侧辅助。
**A**ssist/recovery（UTRG + IP）：低置信重抓；人类干预按动作效价选恢复。
**S**tage-wise score-step graph（SSG）：保留上一轮的评分步骤图/相位图，但把它从“终局门控”改成“全程相位时钟”。
**P**rototype forge（1DVF）：一天一轮的第一抓变体锻造，失败卡回灌训练/上下文/角色标签。

上一轮的 PILOT 组件不丢：PGL（放置目标阶梯）、OPT（少样本放置位姿迁移）、SVL（落点闭环）、NRB（官方备注恢复库）、ICR（上下文检索）全部保留，但降级为“最后一公里”模块，预算不超过 15%。

### 2.1 预期增益（条件性，待调试槽校准）

| 杠杆 | 假设 | 总分增益 |
|---|---|---|
| 第一抓 +10pp | 下游条件成功率 0.5–0.7 | +5–7pp |
| 终局 +5pp（条件） | 到达终局比例 0.3 | +1.5pp |
| 双臂稳定 +3pp（难任务） | 难任务占比 1/4 | +0.75–1.5pp |
| 干预恢复 +10pp（human 轴） | human 轴占 2/10 | +2pp |
| 合计 | 不叠加满额 | +7–10pp |

若基线是占位榜顶部的 29.7%，目标区间 36–39%；若真实基线更低，增益应更大。所有数字都标“待校准”。

### 2.2 本轮明确剪掉的东西

- 情感语音/音频通道：无输入，剪。
- 新 backbone / 模型集成：前三模型架构只差 1.8pp，8 模型总跨度 9.2pp，任务难度跨度 12.6pp；架构不是杠杆，且赛道要求单模型。
- 全 32 任务高保真孪生：不做；只做第一抓的 2.5D 变体。
- 独立双臂模型：不做；只在现有模型上加角色层。
- “终局放置是主闸门”的旧判断：降级为最后一公里。
- 每任务 LoRA / 自由仿真数据 / 运行时 MPC：维持上一轮的剪枝。

## 3. 方案轮廓

离线：
1. 解析 32 个 `info.json` 的 `score_steps`，建 SSG；用 p/q 反推失败阶段（FSP）。
2. 从 32 个数据集标角色/相位；训练角色头 + 抓取置信头。
3. 1DVF 生成第一抓变体；输出失败卡；回灌训练混合与上下文。
4. 解析 human notes，生成 IP 分类标签；1DVF 合成不同速度/方向的干预。

在线（单模型、一个 API）：
1. 语言 → 任务/复述 → SSG 相位时钟。
2. 第一抓：FGS 对侧臂稳定 + 主臂闭合 + 腕部验证；低置信 UTRG 重抓（最多 2 次，时间预算内）。
3. 搬运：SSG 推进；若 human 干预，IP 分类 → 恢复。
4. 最后一公里：PGL/OPT/SVL 放置闭环；NRB 兜底。
5. 输出动作 chunk（EE 优先，双臂；下半身固定/小范围稳定）。

训练：
- Stage 1：官方 33k 行为克隆 + 角色/相位/置信辅助损失。
- Stage 2：1DVF 变体 + 合成干预 + 角色交换/镜像（仅在对称任务）。
- Stage 3：调试槽 A/B → 目标数据补充 → 全量评测。

## 1. 事实核对与纠错

### 1.1 排名规则

- 首页与排行榜页文案：“按平均成功率与步骤分综合排序”。[S1][S4]
- 参赛手册细则（上一轮已核实）：**先按 32 任务总平均成功率排序；成功率相同看总平均步骤分；再相同看提交日期早者**。[S7][S8]
- 本轮处理：以手册为准；首页“综合排序”是模糊表述，不能据此把步骤分当成与成功率同权。**主优化目标仍是成功率，步骤分是 tie-break/部分进展指标。**

### 1.2 8.6pp 的正确读法

设任务成功率 p、平均步骤分 q（0–100）。失败者平均部分分 A：

```text
A = (q - p) / (100 - p) × 100
```

8 模型 × 32 任务均值：p≈25.2，q≈33.8，A≈11.5 分。第一步平均权重 w1≈35.5 分。即便把所有部分分都归给第一步，最多约 32% 的失败者完成了第一步；第一步成功率上界约 49%。

若失败都发生在终局，步骤分应为：

```text
q_terminal = p + (1-p) × (100 - wn) / 100
```

wn 为终局权重，平均约 39.8 分；q_terminal 约 61–85 分，而实际 q 只有 24–41 分。终局最多解释约 20% 的 gap（32 任务平均 19.7%）。**结论：终局是乘数，不是闸门。**

**证据边界**：假设 `score_steps` 为累计计分。info.json 的 32 个任务分值都加总到 100，手册称“步骤分”，这是最自然读法；但仍需调试槽逐步日志确认。[B][D]

### 1.3 终局占比与分类口径

上一轮写“放置/插入/堆叠/闭合类步骤合计约 1910 分，占 59.7%”。本轮用脚本复核：

- 32 任务共 **94 个评分步骤、3200 分**；终局步骤 **1275 分（39.8%）**；最后两步 **2410 分（75.3%）**。[A]
- 终局类型（按任务数与分值）：
  - 放置/堆叠：**16 任务，670 分（20.9%）**
  - 闭合/拉链/锁：**8 任务，275 分（8.6%）**
  - 插入：**2 任务，80 分（2.5%）**
  - 倾倒/转移：**2 任务，100 分（3.1%）**
  - 拔出/取出：**2 任务，90 分（2.8%）**
  - 其他（翻环/叠毛巾）：**2 任务，60 分（1.9%）**
- 结论：**“终局=39.8%”成立；“放置/插入/堆叠/闭合=59.7%”是跨所有步骤的手工归类，不能再当作终局占比使用。** 本轮统一用“终局 39.8%、最后两步 75.3%、终局类型 16/8/2/2/2/2”这组口径。[A]

### 1.4 双臂统计与阈值

### 4.3 训练

**Stage 1：官方数据行为克隆 + 辅助头**

- 输入：4 路 RGB（可 resize 到 320×240/224×224）、双臂 EE/joint、夹爪、语言；`obs_delta_indices` 建议每路堆叠 2–4 帧。
- 输出：动作 chunk（16 步左右）；角色 logits（4 类）；相位 logits（任务步骤数）；抓取置信（0–1）。
- 损失：`L = L_action + λ1 L_role + λ2 L_phase + λ3 L_conf + λ4 L_consistency`。
- 角色伪标签：由演示的 EE 运动、夹爪开合、与目标/容器的相对位姿自动生成；只保留高置信帧（例如运动能量/夹爪变化明确的帧）。
- 相位伪标签：用 SSG 步骤文本 + 演示关键帧/速度拐点对齐；不要求完美，只要求“第一抓/搬运/终局”三段可分。

**Stage 2：1DVF 变体 + 合成干预 + 角色增强**

- 第一抓变体：物体位姿/干扰物/背景/光照/容器位姿/人手遮挡；每任务 100–300 个；用运动学碰撞检查过滤不可达/穿插。
- 角色增强：对称任务做左右交换/镜像；非对称任务只做“稳定臂位置扰动”，避免生成不可能的场景。
- 干预合成：人手从不同方向/速度进入，标签为 `displace/undo/remove/add/occlude`；训练 IP 头。
- 训练方式：在 Stage 1 权重上继续 BC + 辅助损失；变体数据只占 20–30%，避免 2.5D 伪影主导。

**Stage 3：调试槽 A/B + 目标数据补充**

- 选 2–3 个任务（建议 T01 HangCup、T09 ToolboxStorage、T26 PlugInEthernet，覆盖单手/闭合/插入）。
- 每个任务 10 次调试；对比 baseline / FGS / FGS+UTRG / 全量。
- 只把“真实第一抓成功/失败”的帧回灌，不把调试槽数据直接大规模训练（样本少、易过拟合）。

### 4.4 推理伪代码

```python
def act(obs):
    task = match_task(obs.language, paraphrases_160)      # 160 条复述
    phase = ssg.phase(task, obs)                          # 步骤/相位
    role_logits, conf = model.aux_heads(obs, phase)       # FGS + 置信
    if phase == "first_grasp":
        if role_logits.stabilizer_side != active_side:
            yield model.stabilize(obs, role_logits)        # 对侧臂稳定
        action = model.grasp(obs, role_logits)
        yield action
        if wrist_verify(obs) < CONF_THRESH:
            yield model.retract(obs)                       # UTRG
            yield model.regrasp(obs)                       # 最多 2 次
        else:
            phase = "transport"
    elif phase == "transport":
        yield model.transport(obs, phase)
    elif phase == "last_mile":
        yield pilot_lm.place(obs, pgl, opt, svl)           # 最后一公里
    if detect_human_intervention(obs):
        kind = ip.classify(obs)                            # undo/displace/remove/add/occlude
        yield recover(kind, obs)                           # 回退/重定位/重规划/等待
```

### 4.5 接口与部署

- **动作空间**：优先 `ee`（双臂 EE 位姿 + 夹爪），落点精度高；下半身固定/小范围稳定。若 API 对双臂 EE 支持不完整，再退 `joint`。
- **观测裁剪**：`obs_delta_indices` 包含 4 路 RGB、双臂 EE/关节、夹爪、语言；每路堆叠 2–4 帧；`image_resize` 320×240 或 224×224。
- **chunk**：`action_chunk_size=16`；推理频率 10–15Hz；180s 内至少留 30s 给重抓/恢复。
- **单模型**：所有头共享 backbone；角色/相位/置信/干预头都是小头；不使用外部 API/模型集成。
- **安全**：工作空间限制、碰撞自检、夹爪力限、重抓次数上限、超时回退到“保守放置/终止”。
- **延迟**：WLA-1.0-Base 6B 在单张 24GB GPU 上量化推理可行；若延迟 >100ms/step，减小图像分辨率/帧堆叠，或改用 Wall-OSS-0.5 4B。

## 5. 创新点卡片

### 5.1 FSP · Failure-Stage Profiler（P0）

- **动机**：上一轮把终局当主闸门，预算错配。用公开 `score_steps` + p/q 反推失败阶段，先打最早的高损失步骤。
- **与现有差异**：不是静态权重分析，也不是笼统的“失败恢复”；它是**从聚合分数反推阶段分布**，用于预算分配和任务选择。类似“故障树/贝叶斯反推”，但输入是官方评分结构。
- **技术可行性**：只需 32 个 info.json + 占位榜 p/q；公式简单；可在 1 天内产出 per-task 先验。真正的校准用调试槽逐步日志（若平台提供）或真机视频人工标注。
- **所需资源**：1 人 × 3–5 天；无 GPU；官方数据/榜。
- **落地步骤**：① 解析 score_steps；② 计算 A、A/w1、终局解释上限；③ 按“最早高损失”排序任务；④ 选 5–8 个任务做首批 1DVF/FGS；⑤ 调试槽验证排名。
- **风险**：累计计分假设不成立；占位榜非真实；聚合分数无法唯一反推阶段。缓解：用逐步日志/视频校准；把 FSP 当“先验”而非“结论”；设置 go/no-go。
- **验收**：FSP 预测的“第一抓最难”任务与调试槽第一抓成功率排序 Spearman >0.5；否则降级为启发式。

### 5.2 FGS · First-Grasp Stabilization（P0）

- **动机**：第一抓是主闸门；29/32 任务双臂都在动；名义单手任务里第二臂也在动，但未被显式用作稳定器；模型级双臂 deficit 只在少数模型出现，说明“会用第二臂”是能力缺口而非任务难度。
- **与现有差异**：
  - BiCICLe：把双臂当 leader-follower 多智能体，做双臂任务；FGS 把第二臂当**第一抓稳定器**，也用于名义单手任务。
  - MA-VLA：多臂原子动作分配 + Arm Shuffle；FGS 不重分配任务，只加角色/相位/跨臂相对位姿，单模型小改。
  - FineART：密集子任务标注 + 子任务预测；FGS 用角色伪标签 + 相位时钟，不要求人工标注 53 万子任务。
- **技术可行性**：官方 33k 演示可直接标角色；WLA-1.0-Base/Wall-OSS-0.5 都可加小头；EE 动作空间支持双臂；1DVF 提供第一抓变体。
- **所需资源**：8×H100 × 2–3 周；1–2 名工程师；官方数据；调试槽 1–2 次。
- **落地步骤**：① 角色伪标签（运动/夹爪/接触）；② 加角色 token/跨臂相对位姿/phase token；③ Stage 1 BC + 辅助损失；④ 对侧臂稳定 primitive（几何 heuristic + 学习 affordance）；⑤ 腕部验证 + UTRG；⑥ 调试槽 A/B。
- **风险**：角色标签噪声；第二臂碰撞/遮挡腕部相机；角色交换生成不可能场景；单模型约束。缓解：高置信帧、碰撞自检、只在对称任务交换、相机感知稳定位姿。
- **验收**：调试槽第一抓成功率 +10pp；全任务成功率 +3pp 以上；碰撞率不升；180s 内完成率不降。

### 5.3 1DVF · One-Day First-step Variant Forge（P0）

- **动机**：快速原型的瓶颈不是“造全孪生”，而是“每天能否生成针对第一抓的 OOD 变体并回灌”。官方演示 + 2.5D 编辑足够测试第一抓。
- **与现有差异**：不是通用图像增强，也不是全物理孪生；它**只回放第一段**，用运动学碰撞检查过滤，输出“失败卡”而不是绝对成功率。类似 ASPIRE 的快速技能原型 + Kintsugi 的失败回放，但更窄、更便宜。
- **技术可行性**：LeRobot 数据有 EE 位姿/相机；SAM/GroundingDINO 可分割；2.5D 分层/修复可用开源工具；PyBullet/MuJoCo 可做碰撞/可达性；一天一个任务批可行。
- **所需资源**：1 名工程师 × 2 周搭建；1 张 24–48GB GPU；无大规模仿真集群。
- **落地步骤**：① 解析任务/第一步/目标物体；② 选 5–10 条演示；③ 生成变体（位姿/干扰/背景/光照/容器/人手）；④ 运动学过滤；⑤ 回放第一段/抓取评分；⑥ 输出失败卡；⑦ 回灌训练/上下文/角色标签。
- **风险**：2.5D 伪影；回放不真实；变体与真实评测分布不匹配；物体分割错误。缓解：只做相对排序；每周用调试槽校准 1 次；人工审核失败卡；限制变体幅度。
- **验收**：1DVF 变体上的第一抓成功率与调试槽第一抓成功率排序一致（Spearman >0.5）；失败卡能预测至少 3 类真实失败；单任务批 ≤1 天。

### 5.4 UTRG · Uncertainty-Triggered Re-Grasp（P1）

- **动机**：第一抓失败往往在搬运中才暴露；腕部相机 + 动作熵可以在闭合后立即判断“抓稳了吗”，早重抓比失败重来便宜。
- **与现有差异**：不是盲目 retry；它用腕部视觉/接触/动作熵做置信估计，只在低置信时重抓，并受时间预算约束。
- **技术可行性**：腕部相机已有；演示可提供“抓稳/滑移/空抓”标签（用夹爪开度 + 物体位姿变化弱标注）；小分类头即可。
- **所需资源**：1 人 × 1 周；无新数据；复用 FGS 训练管线。
- **落地步骤**：① 定义置信特征（腕部图像、夹爪开度、物体相对位姿、动作熵）；② 弱标注/1DVF 合成；③ 训练分类头；④ 阈值校准（调试槽）；⑤ 重抓策略（最多 2 次，时间预算 30s）。
- **风险**：误判导致浪费时间；重抓碰撞；阈值任务依赖。缓解：保守阈值；重抓前后退；按任务校准；超时回退。
- **验收**：第一抓失败中 30% 能在 10s 内恢复；整体成功率 +1–2pp；平均时长不增 >10%。

### 5.5 IP · Intervention Prosody/Intent（P1）

- **动机**：human 轴 2/10；官方 notes 给了剧本；把人类干预当成“非语音的情感/意图”信号，按类型恢复，比统一异常处理更省尝试。
- **与现有差异**：NRB 是“备注回放”，IP 是“语义分类 + 策略选择”；不是音频情感识别（无音频通道），而是动作效价（速度/方向/平滑度/是否带走）。
- **技术可行性**：notes 可弱标注；1DVF 可合成不同速度/方向的人手；光流/手部分割/物体位移特征可用；小分类头。
- **所需资源**：1 人 × 1 周；官方 notes；1DVF 合成数据。
- **落地步骤**：① 解析 notes → 类别；② 1DVF 合成干预；③ 训练分类头；④ 接 SSG/NRB 恢复；⑤ 调试槽 human 轴验证。
- **风险**：notes 稀疏/歧义；真实人行为与合成不同；误判。缓解：保守阈值；通用恢复兜底；只在高置信时切换策略。
- **验收**：human 轴恢复成功率 +10pp；整体 +1–2pp；误恢复率 <10%。

### 5.6 PILOT-LM · 最后一公里（P2，保留）

- **保留组件**：PGL（放置目标阶梯：槽位→锚点→位姿）、OPT（少样本放置位姿迁移）、SVL（落点闭环/稳定判定）、NRB（官方备注恢复库）、ICR（上下文检索）。
- **降级原因**：终局只解释 ≤20% 的 gap；先把第一抓做稳，再花 15% 预算优化最后一公里。
- **使用条件**：第一抓/搬运成功率达到阈值（建议调试槽 ≥60%）后，才把预算从 15% 提高到 25%。
- **验收**：终局条件成功率 +5pp；整体 +1–1.5pp；不拖慢第一抓。

### 5.7 剪枝清单（P3）

| 剪枝项 | 原因 | 处置 |
|---|---|---|
| 情感语音/音频通道 | 观测无音频；语言固定字符串 | 不做；只保留 IP |
| 新 backbone / 模型集成 | 前三模型差 1.8pp；单模型规则 | 不做 |
| 全 32 任务高保真孪生 | 成本高；第一抓只需 2.5D | 不做 |
| 独立双臂模型 | 任务级双臂无难度差；单模型 | 不做；加角色层 |
| 终局放置为主闸门 | 只解释 ≤20% gap | 降级为最后一公里 |
| 每任务 LoRA | 32 模型不合规/易过拟合 | 不做；单模型 + 小头 |
| 自由仿真数据/运行时 MPC | 与第一抓闭环无直接关系 | 维持剪枝 |
| 大规模外部数据 | 合规不确定；官方 33k 足够 | 先不用；待规则确认 |

### 6.6 统计与置信区间

- 每任务 10 次 → 成功率粒度 10%；p=0.3 时 95% Wilson CI 约 ±0.27，单任务不可靠。
- 结论必须看 **32 任务平均 + 配对任务**，不要只看单任务。
- 占位榜 8×32 矩阵只用于先验，不用于显著性检验。
- 调试槽样本少，只做方向性判断；正式结论用计分跑。

| 第二臂碰撞/遮挡 | 中/高 | 碰撞自检；相机感知稳定位姿；只在安全任务启用 |
| UTRG 误判/超时 | 中/中 | 保守阈值；重抓上限 2 次；30s 时间预算；超时回退 |
| IP 误分类 | 中/低 | 高置信才切换；通用恢复兜底；human 轴样本少 |
| 6B 模型延迟 | 中/中 | 量化/降分辨率/减帧堆叠；备选 Wall-OSS-0.5 4B |
| 单模型合规 | 低/高 | 所有头共享 backbone；不调用外部模型；提交前审查 |

### 8.2 规则/合规风险

- 外部数据/预训练权重是否允许：手册只抓到 2.1/2.2，需官方确认；本轮不依赖外部数据，WLA-1.0-Base 是 Unitree 公开 Apache-2.0 权重。[S7][S8][D]
- 单模型/单 API：所有模块共享一个 backbone；角色/相位/置信/干预都是小头；不做模型集成。
- 远程评测网络/延迟：本地服务需稳定；`action_chunk_size`/分辨率可调；准备 fallback 策略。
- 安全：真机 180s；重抓/恢复必须有超时和碰撞保护。

### 8.3 进度风险

- 1DVF 搭建可能超 2 周：先用“手工变体 + 回放”MVP，不等全自动。
- FGS 训练可能不收敛：先做角色 token 的轻量 adapter，不动 backbone；必要时只做对侧臂 heuristic assist。
- 调试槽排期不确定：W1 就预约；没有槽就用离线回放做相对排序。

## 10. 开放问题

1. **步骤分语义**：累计计分、最高步骤、还是每步独立成功率？这决定 FSP 是否成立。需手册 3.x 或调试槽逐步日志。
2. **5 条复述是否均匀采样**：评测语言是固定一条还是 160 条中采样？影响语言鲁棒性预算。
3. **外部数据/预训练权重是否允许**：手册未抓全；WLA-1.0-Base 是 Unitree 公开权重，但规则是否允许需确认。
4. **调试槽次数/排期**：每队几次？能否按任务预约？决定真机 A/B 频率。
5. **榜单是否真实**：`generated_from=gen_leaderboard.py`、视频占位；如果是预热数据，所有绝对排名都不能引用。
6. **截止日期/赛程**：未找到官方时间线；需邮件/手册确认。
7. **双臂 EE 是否都支持**：`control_space=ee` 是否接受双臂 EE + 夹爪？若不支持，FGS 需退 joint。
8. **人类干预时机**：notes 是“第几步之后”还是“随机时刻”？影响 IP 的触发逻辑。
9. **WLA-1.0 是否见过 UniBot 任务**：若 Unitree 自家模型已在这些任务上训练，基线/微调策略需调整（可能是优势，也可能是泄漏风险）。
10. **评测初始场景分布**：是否与数据集同分布？位置/背景/干扰物的采样范围决定 1DVF 变体幅度。
