# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配多模态交互消歧」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「用户需求分析」×「热管理」）

> R69 把不确定性一分为二：aleatoric（收紧）与 epistemic（去问）。但它仍默认两件事是**给定且免费**的：**目标/需求是确定的**（风险偏好、任务优先级、什么叫「干净」都由部署者写死），**算力与交互是免费的**（多采 K 条轨迹、算 Hutchinson 散度、解码问句、反复求证，都不计代价）。这两条默认在真实系统里恰恰最脆弱。
>
> 本轮两个灵感正好各补一个默认：
> - **用户需求分析**指出：需求不是常量，而是**待获取、待协商、待验证、待追溯**的对象；不同用户对风险/速度/舒适/能耗的偏好不同，且**不可从环境观测**，只能问、只能从行为推断。于是出现第三种不确定性 **U_req（需求/偏好歧义）**：它不是「世界是哪个」，而是「我该服务谁、服务到什么程度」。
> - **热管理**指出：算力、交互、执行**都要发热**；热又反过来抬高噪声、限制时钟、削弱执行器、收紧安全包络。R69 的「resolution bonus」不是白得的，它是**向未来借用热余量**——先花，后用冷却时间还。于是不确定性消解变成一个**热力学交易**：以焦耳计价、以开尔文结算。
>
> 核心命题：**把需求歧义作为一等公民，把热预算作为一等资源；用「用户需求分析」决定值不值得问、问什么、能否兑现，用「热管理」决定问得起多少、何时该停下来冷却。二者不是两层约束，而是一个双向闭环：需求设定热预算，热状态界定可兑现需求的边界。** 命名 **WARM-RAS**（Watt-Aware Requirement Management for Risk-Adaptive Safety）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**我到底在为谁、以什么代价、兑现什么**」——不确定性不仅是刹车与提问，也是一张用户开出的需求清单和一份会发热的账单。

## 0. 直觉与动机

**灵感 1（用户需求分析 → 需求是第三种不确定性的来源）**
直觉：R69 的 U_epi 是「世界有歧义」（绕左还是绕右）。但还有一类歧义是「**我不知道你想要什么**」：同一条走廊，赶时间的人希望你快，怕摔的人希望你稳；同一个「打扫干净」，有人指地面无尘，有人指台面无物。这类歧义**无法通过看环境消解**——环境里没有写用户效用函数。它只能通过**问（成对比较/排序）、看（示范）、协商（预算/约束）**获得，而且常常**问不完、问不准、用户会变**。把它硬塞进 R68 的 λ_floor（一律收紧）会让系统对所有人都过度保守；把它当成 R69 的 U_epi（去问世界）则是问错了对象。所以必须单列 **U_req**，并配一套「运行时需求工程」：获取、协商、验证、追溯。

**灵感 2（不是所有需求歧义都值得问 → 只有「会改变决策」的才值钱）**
直觉：两个用户的偏好确实不同，但如果当前情境下他们的偏好**导出同一个安全动作**，问就是浪费。R69 已意识到「可分才可约」，本轮把它推到需求侧：需求歧义的价值不是熵，而是**后悔（regret）**——按后验最优动作执行，相对「知道真实偏好」会损失多少。若各偏好在候选动作集上**决策等价**，U_req=0，无论偏好分布多分散。这把「用户需求分析」从「尽量问清楚」变成「只在决策边界附近问」，天然抗过度打扰。

**灵感 3（热管理 → 不确定性消解是一笔热力学账单）**
直觉：R69 的所有聪明机制都在烧算力：K 条流采样、Hutchinson 散度、问句解码、反复交互。算力→发热→（i）DVFS 降频使延迟上升、每轮可用 K 变小；（ii）温度上升使传感器噪声变大、执行器力矩下降；（iii）表面温度与风扇噪声本身成为**用户可感知的需求项**。于是存在一个正反馈的危险回路：**越不确定越想多算 → 越算越热 → 越热越不确定 → 越想多算**。R70 必须把热当成**守恒的、有惯性的、慢可观测的**资源，并证明闭环不发散——否则 R69 的「多问多看」会把系统烤熟。

**灵感 4（双向闭环 → 需求与热互为约束，而非上下层）**
直觉：直觉上热管理像「下层执行约束」、需求分析像「上层目标」。但真实系统里二者双向耦合：需求**设定**热预算（「我要安静、要能用 8 小时」直接约束风扇与算力档位），热状态**界定**可兑现需求（「满速跑 8 小时」在给定散热下不可行）。于是需要一个**热-需求一致性**：系统不能悄悄接下做不到的需求，也不能为省热而默默降低服务而不告知。正确做法是**在运行时做可行性分析与协商**：先验算需求在热预算内是否可兑现，不可兑现就提出 Pareto 最小的放宽方案并说明，而不是「答应了再违约」。这把经典需求工程的「可行性/协商/可追溯」搬到了运行时。

**灵感 5（热也是缓变故障的物理载体 → 正面回应 R69 的盲点）**
直觉：R69 用动作似然通道对抗「标定吸收」，但它没回答**热从哪来、为什么会被吸收**。事实上热漂移正是最典型的慢变故障：它同时抬高传感器残差（可被标定吸收）与削弱执行器（不会被传感器标定吸收，却会被动作似然部分掩盖）。WARM 增加第三条独立通道：**热模型残差 r_th = 实测温度 − 预测温度**。若 r_res≈0 而 r_th 与执行器偏差同向升高，则更可能是「真实热载荷/散热受阻/执行器摩擦」而非传感器偏置。热是可测的物理量，这让「缓变故障」第一次有了可落地的物理第二意见。

## 1. 形式化定义（增量：定义 310–325）

**定义 310（WARM-RAS 总览）** WARM-RAS = (RPM, CRU, REC, RRN, TSO, TCE, DSA, TCC, TRC, THM, RAS-WM‡)。五不变式：
(i) 继承 R69 实时流零学习写操作（定义 293-i）；
(ii) **热预算硬约束**：任意决策窗口内累计热注入 ∫Q ≤ 热余量预算（定义 319–320），越界即进入冷却模式；
(iii) **需求纪律**：未经验证/未协商的单句需求不得定案；不可兑现需求不得静默接受；
(iv) **抗升级**：计算预算对温度单调不增（定义 319），禁止「越热越算」；
(v) **安全单调**：减少计算/交互/执行强度永不增加风险（定理 19）。

**定义 311（需求空间与运行时后验 RPM）** 用户需求 θ_u ∈ Θ 参数化效用 J_{θ_u}(s,a)（风险偏好、速度-安全权重、舒适/噪声/续航权重、任务完成度语义）。维护后验 q_t(θ_u)。需求证据源：成对比较 b=(a_i ≻ a_j)、示范 d、显式约束 c（如「表面温度 < 43°C」）、历史跨会话先验。θ_u 同时含一个**热偏好分量** θ_u^{th}（可接受表面温度、噪声上限、续航要求）。

**定义 312（决策等价与后果加权需求不确定性 CRU）** 令 a*(q)=argmax_a E_{θ~q}[J_θ(s,a)]。需求后悔
R(q) = E_{θ~q}[ max_a J_θ(s,a) − J_θ(s,a*(q)) ]。
定义 U_req := R(q)。若 ∀θ∈supp(q) 的候选动作排序相同，称 q **决策等价**，必有 R(q)=0。信息动作 e 的需求信息增益 VoI_req(e)=R(q)−E_{y~p(·|e)}[R(q')]。⇒ 只问「会改变动作选择」的需求。

**定义 313（热状态、集总热模型与观测器 TSO）** 节点温度 T∈ℝ^m，热容 C=diag(c_i)，导热/对流矩阵 G=G^T⪰0（含环境耦合），热源 Q=Q_compute+Q_act+Q_int。连续动力学 C Ṫ = −G(T−T_amb)+Q；离散 T_{k+1}=T_k+Δt C^{-1}(−G(T_k−T_amb)+Q_k)。G⪰0 ⇒ 无热源时向 T_amb 指数收缩。观测器（卡尔曼/龙伯格）输出 T̂ 与协方差 Σ_T；前向仿真得预测轨迹 {T̂_{t+j}} 与热余量 Ĥ。

**定义 314（热-算力耦合与降级）** 计算能耗 E_comp = K·N_step·c_fwd + n_tok·c_llm；发热 Q_comp=E_comp/Δt。温度经 DVFS 限制时钟 f(T)，延迟 L(T)=L_0 f_0/f(T)；每轮可用采样数 K_max(T)=⌊E_budget(T)/(N_step·c_fwd)⌋（E_budget 随 T 递减）；传感器噪声 Σ_s(T) 随 T 增；执行器力矩上限 τ_max(T) 随 T 减；表面温度 T_surf(T) 与风扇噪声 n_fan 为用户可感需求项。

**定义 315（热余量与热-认知价格 TCE）** 热余量 H(T)=T_limit−max_{j≤H}T̂_{t+j}（逐轴取最紧）。信息/执行动作 x 的热价 ΔE(x) 为其焦耳能耗。定义热-认知效率 ρ(x)=VoI(x)/ΔE(x)（nats/J）。选 x*=argmax ρ(x)，s.t. H(T)−ΔT(x)≥0 且预算未越界。**H<0 或 ρ≤0 ⇒ 不花这笔热**。

**定义 316（降级感知风险底 DSA）** 风险底从 λ_floor(U) 推广为 λ_floor(T,U)：安全包络 ε(T) 随 T 单调收缩，λ_floor(T,U) 随 T 与 U 单调不减；执行指令按 τ_max(T) 截断。⇒ 热越高，系统自动更慢、更稳、更不激进。

**定义 317（需求获取控制器 REC）** 候选获取动作 e∈𝒜_elicit（成对比较问句、示范请求、约束澄清、冷却后追问）。e* = argmax_e [VoI_req(e) − c_social(e) − c_thermal(e)]，s.t. 决策相关性 R(q)>τ_r、可辨识性（e 能区分候选 θ）、预算与热余量允许。**不可辨识**（任意可行 e 都无法区分 θ_i,θ_j 且二者决策不同）⇒ 不无限追问，改用**最坏情形鲁棒**需求（对应 R69「模糊不可分即保守」）。

**定义 318（运行时需求可行性与协商 RRN）** 给定 q 与热模型，可行需求集 Θ_feas={θ: ∃π 满足 θ 且 P(热违规)≤δ}。若 q 的质量较多落在 Θ_feas 外，提出 Pareto 最小放宽 θ'=Proj_{Θ_feas}(θ)（沿用户声明的重要性加权），经证据纪律确认后生效；用户不可达 ⇒ 取「可兑现的最小服务」并显式降级，**禁止静默违约**。

**定义 319（热-算力调速器与抗升级 TCC）** 计算预算 B_comp(T) 对 T 单调不增；硬不变量 H(T)−ΔT≥0。当 T→T_limit 或预测将越界：进入 **COAST/COOL** 模式——K→1、暂停需求获取、降低非必要执行、优先散热，λ 单调不减。热债（定义 320）未偿清前不得升档。

**定义 320（跨时热信用与冷却调度）** 定义热信用 c(t)=∫_0^t G(T−T_amb) dτ（可耗散热）。任意窗口可行当且仅当 ∫Q dτ ≤ C(T_limit−T_0)+∫G(T_limit−T_amb)dτ（能量平衡）。R69 的 resolution bonus 记为**向未来借的热贷**：升 K/多问先透支，须在后续冷却窗口偿还；债务上限 d_max 约束一次性超支。

**定义 321（热-需求一致性不动点 TRC）** 令算子 F:(q,π)↦(q',π')：π' 为 q' 下热可行最优策略，q' 为在 π' 的热预算内最优获取后的后验。一致解为使 F 不动点的 (q*,π*)。压缩条件下唯一（Blackwell 充分条件 + 获取收益递减）；否则用**阻尼迭代**：每步安全优先、需求次之，且不允许 q 跨步剧烈跳变（防振荡）。

**定义 322（热残差反吸收 THM）** 热模型残差 r_th = T̂^{meas}−T̂^{pred}（观测器新息）。与 R69 的 (r_res, Δa) 组成三元：**r_res↓ 且 Δa↑ 且 r_th↑（同向）⇒ 热载荷/散热受阻/执行器摩擦**，而非纯传感器偏置；r_th 高但 r_res、Δa 不高 ⇒ 热模型失配。热通道不可被传感器标定吸收，因为它以执行器与环境耦合为参照。

**定义 323（参与式审计与威胁模型扩展）** WQAuditor 审计：过度追问、诱导式问句、单源采纳需求、接受不可兑现需求、热债超限、COOL 期仍升档。威胁：**热攻击**（热风枪/堵风道/计算型 DoS 逼降频）、**需求投毒**（策略性谎报偏好以换取更激进行为）、**热侧信道**（由热/噪声反推用户画像）。并入 AIC-WARM = AIC-FLUID × ℰ_thermal × ℰ_req。

**定义 324（证书 J_WARM）** J_WARM = (J_FLUID, T_p95, H_min, E_used, debt_max, req_regret_bound, req_feasibility, elicit_log_hash, thermal_trace_hash, warm_ver)。Valid ⇔ Valid(J_FLUID) ∧ H_min≥0 ∧ 需求证据纪律 ∧ 热债未越界 ∧ 需求可追溯（每个动作可追到需求条款）。

**定义 325（两级→三级保守退避）** 消解成功：λ=λ_floor(U_ale)+g_ε(T)（resolution bonus 扣除热安全项）；req 不可辨识/热不可行/COOL 期：λ=λ_floor(U_ale+U_epi+U_req, T)。⇒ FLUID/R68 为「需求确定 ∧ 热无限」边界；安全侧永不弱于 R68/FLUID。

# IP-264/265 RPM+CRU：需求后验与后悔型需求不确定性
class RequirementPosterior:
    def update(self, evidence):                  # 成对比较/示范/约束
        self.q = bayes(self.q, evidence)
    def regret(self, candidates, s):
        a_star = argmax_a(E_th[J(th, s, a) for th in self.q])
        return E_th[max_a J(th, s, a) - J(th, s, a_star)]   # 决策等价 -> 0

# IP-268/269 TSO+TCE：热余量与热-认知价格
class ThermalObserver:
    def predict(self, plan, H):                  # 前向仿真热模型
        T = self.T_hat.clone()
        for u in plan[:H]:
            T = T + dt * inv(C) @ (-G @ (T - T_amb) + heat(u))
        return T, headroom(T, T_limit), cov_T
def thermally_affordable(x, T_hat, budget):
    T_pred, H, _ = tso.predict(plan_of(x), H=h)
    return (H - dT(x) >= 0) and budget.allow_energy(E(x)) and not debt.over(d_max)

# IP-266 REC：只在「改变决策」处问，且算得起才问
def choose_elicit(req, s, T_hat, budget):
    if req.regret(candidates, s) <= TAU_R: return None        # 决策等价 -> 不问
    best = None
    for e in elicit_candidates(req, s):
        if not req.identifiable(e): continue
        if not thermally_affordable(e, T_hat, budget): continue
        gain = req.regret(candidates, s) - E_y[req.regret_after(e, y)]
        score = gain - social_cost(e) - joule_cost(e)
        if best is None or score > best.score: best = (e, score)
    return best if best and best.score > 0 else None

# IP-267 RRN：可行性分析与协商，禁止静默违约
def negotiate(req, T_hat, delta):
    if req in feasible_set(T_hat, delta): return req
    return pareto_min_relax(req, feasible_set(T_hat, delta))   # 需证据纪律确认

# IP-271 TCC：抗升级调速器（温度↑ => 预算↓，硬余量不变量）
def govern(T_hat, H):
    B = B0 * clip((T_soft - T_hat)/(T_soft - T_amb), 0, 1)     # 单调不增
    if H < margin or debt.over(d_max): return COAST(B=min(B, B_min))
    return NORMAL(B)

# IP-277 主闭环（继承 FLUID/R68，插入热-需求层）
def WARM_RAS_round(M, obs):
    z, o = M.mtm.forward(...); c, U_cal, thr = M.cof.step(...)
    T_hat, H, _ = M.tso.predict(M.last_plan, h=M.vista.H)
    B = M.tcc.govern(T_hat, H)                     # 1) 先定热预算
    K = 1 if (M.fmp.mode_head(z) < TAU_MODE or B.small) else 4
    samples = M.fmp.sample(o, K)
    U_ale, U_epi, modes, _ = M.aud.decompose(samples, z, M.fmp.mode_head)
    # 2) 需求层：只在决策相关处获取/协商
    U_req = M.rpm.regret(modes, s)
    e = M.rec.choose_elicit(M.rpm, s, T_hat, B) if U_req > TAU_R else None
    if e is not None:
        M.rpm.update(M.cia.execute(e)); U_req = M.rpm.regret(modes, s)
    req = (M.rrn.negotiate(M.rpm.map(), T_hat, delta)
           if not M.rrn.feasible(M.rpm.map(), T_hat) else M.rpm.map())
    # 3) 热残差反吸收（第三意见）
    slow = (M.fma.flow_anomaly(...) > TAU_FMA) and (M.last_r_res < TAU_RES)
    hot_fault = slow and (M.thm.innovation() > TAU_TH)
    # 4) 热感知风险底 + 保守退避
    U_floor = U_ale + (U_epi if e is None else 0.0) + (U_req if e is None else 0.0)
    lam = max(M.efs.risk_scale(...), lam_floor(U_floor, T_hat))
    k = M.c_ras_wm.certified_prefix(M.ach.propose(...), ..., wm_preds)
    if hot_fault or B is COAST:
        lam = max(lam, 0.8); k = min(k, k_thermal_shrink(T_hat))
    mode = select_mode(modes, U_epi, lam, req)      # 需求只影响模态选择/裕度
    tau = M.pi_sigma.prefix_dispatch(mode.a[:k]) * lam
    M.tce.charge(E(e)+E_compute(K)+E_act(k))        # 记热债
    M.wqa.submit_async(e, req, U_req, T_hat, H)
    return k, lam, mode, (U_ale, U_epi, U_req, req)

## 3. 推导

**引理 19（热预算的守恒上界与 resolution bonus 的贷款性质）** 由 C Ṫ=−G(T−T_amb)+Q，对任意窗口 [0,H] 积分并令 T≤T_limit：∫_0^H Q dt = C(T(H)−T(0)) + ∫_0^H G(T−T_amb)dt ≤ C(T_limit−T(0)) + G(T_limit−T_amb)H。故可注入热量（从而可购买的 VoI、K、交互次数）被热容余量与可耗散热**双重上界**；R69 的 resolution bonus 消耗的是该上界中的「额度」，先花后还，非凭空产生。

**引理 20（后悔型需求不确定性界定决策损失且决策等价归零）** 对任意 q，按后验最优 a*(q) 执行的期望效用损失恰为 R(q)；且 R(q)=0 ⇔ q 在候选动作集上决策等价。因此以 R 而非熵度量 U_req 是**紧的**：既不高估「分布很散但决策一致」，也不低估「分布集中但恰好跨决策边界」。系：需求获取的价值上界为 R(q)，超过该上界的追问必然亏本。

**引理 21（热残差对降级/热载的判别性与反吸收）** 设传感器标定可吸收温度相关的加性偏置（使 r_res≈0），但执行器力矩 τ_max(T) 与散热通量 G(T−T_amb) 通过**能量守恒**进入热观测器。热模型残差 r_th 的期望偏移 ≥ c_τ‖τ−τ_cmd‖ + c_G‖ΔG‖ − √(trΣ_T)，且与传感器标定参数正交（A99：热参数与传感偏置参数可辨识分离）。故 (r_res↓, Δa↑, r_th↑) 判别「热载/散热受阻/执行器摩擦」，补 R69 的 FMA 只测行为自洽的不足。

**定理 18（WARM 严格包含 FLUID 与 R68）** 在 A99–A101（热模型 Lipschitz、可耗散有界、需求后悔有界）下，WARM 任意状态期望风险 ≤ FLUID；当热预算无限（T≪T_limit 且 G 不受限）且需求后验决策等价（U_req=0）时，WARM 逐指令退化为 FLUID；FLUID 在 VoI≤成本 时再退化为 R68。故 R68 ⊂ FLUID ⊂ WARM 为边界退化链，安全侧逐层不让步。

**定理 19（热-算力闭环有界且安全单调）** 若计算预算 B_comp(T) 对 T 单调不增、λ_floor(T,U) 对 T 单调不减、且硬不变量 H−ΔT≥0 被强制，则：
(i) 温度有界 T≤T_limit（能量平衡 + 不变式）；
(ii) 正反馈「越热越算」被切断——温度上升只能减少计算，不会增加，闭环进入 COAST 收敛到安全平衡；
(iii) 安全单调：任意减少 K、交互或执行强度不增加风险；
(iv) 热债未清不得升档 ⇒ 无跨时振荡。
系：只要调速器是「温度非增预算」的，R69 的「多问多看」不会把系统烤熟。

**推论（热-需求一致性存在性）** 在 Θ、热状态空间紧，效用与热映射连续，获取收益随提问递减（次模）下，TRC 算子 F 存在不动点；若进一步 F 为压缩，则一致解唯一，阻尼迭代收敛。

## 6. 本轮最大风险

**一句话**：WARM-RAS 把安全性押在「热模型足够准、能预判余量」上——但**热是系统中最慢、最不可辨识、最容易被接触/对流/环境扰动的量**，一次模型失配就会让系统误以为自己还有余量而去购买更多 VoI，而**热惯性意味着等观测器发现时，安全裕度已经被提前花掉**；也就是说，**「精打细算地发热」可能比「根本不算」更危险，因为它给了系统一种有据可依的过度自信**。

# IP-264/265 RPM+CRU
class RequirementPosterior:
    def update(self, evidence): self.q = bayes(self.q, evidence)
    def regret(self, cands, s):
        a_star = argmax_a(E_th[J(th,s,a) for th in self.q])
        return E_th[max_a J(th,s,a) - J(th,s,a_star)]      # 决策等价 -> 0

# IP-268/269 TSO+TCE
class ThermalObserver:
    def predict(self, plan, H):
        T = self.T_hat.clone()
        for u in plan[:H]:
            T = T + dt*inv(C) @ (-G@(T - T_amb) + heat(u))
        return T, headroom(T, T_limit), cov_T

    _, H, _ = tso.predict(plan_of(x), H=h)
    return (H - dT(x) >= 0) and budget.allow_energy(E(x)) and not debt.over(d_max)

def choose_elicit(req, s, T_hat, budget):
    if req.regret(cands, s) <= TAU_R: return None
    best = None
    for e in elicit_candidates(req, s):
        if not req.identifiable(e) or not thermally_affordable(e, T_hat, budget): continue
        score = (req.regret(cands,s) - E_y[req.regret_after(e,y)]) - social_cost(e) - joule_cost(e)
        if best is None or score > best.score: best = (e, score)
    return best if best and best.score > 0 else None

def negotiate(req, T_hat, delta):

## 4. 推导

**引理 19（热预算守恒上界 / resolution bonus 是贷款）** 积分 `C Ṫ=−G(T−T_amb)+Q` 并用 `T≤T_limit`：`∫Q dt ≤ C(T_limit−T_0)+G(T_limit−T_amb)H`。故可购买 VoI/K/交互的热量被「热容余量 + 可耗散热」双重上界；R69 的 resolution bonus 先透支、须在冷却窗口偿还。

**引理 20（后悔型 U_req 紧且决策等价归零）** 按后验最优动作的期望效用损失恰为 `R(q)`；`R(q)=0 ⇔` 候选动作排序一致。用 R 而非熵度量既不高估「散而一致」也不低估「集中但跨决策边界」。系：获取价值上界为 `R(q)`，超过必亏。

**引理 21（热残差反吸收）** 传感器标定可吸收温度相关加性偏置（`r_res≈0`），但 `τ_max(T)` 与 `G(T−T_amb)` 经能量守恒进入热观测器；`r_th` 期望偏移 `≥ c_τ‖τ−τ_cmd‖+c_G‖ΔG‖−√trΣ_T`，且与传感偏置参数正交（A99）。故 `(r_res↓, Δa↑, r_th↑)` 判别热载/散热受阻/执行器摩擦。

**定理 18（WARM 严格包含 FLUID 与 R68）** A99–A101 下 WARM 期望风险 ≤ FLUID；热预算无限且需求决策等价时逐指令退化为 FLUID；FLUID 在 `VoI≤c` 时再退化为 R68。⇒ `R68 ⊂ FLUID ⊂ WARM`，安全侧逐层不让步。

**定理 19（热-算力闭环有界且安全单调）** 若 `B_comp(T)` 单调不增、`λ_floor(T,U)` 对 T 不减、硬不变量 `H−ΔT≥0`： (i) `T≤T_limit`；(ii) 切断「越热越算」，闭环收敛到 COAST 安全平衡；(iii) 减少 K/交互/执行强度不增风险；(iv) 热债未清不升档 ⇒ 无跨时振荡。系：R69 的「多问多看」不会把系统烤熟。

**推论（热-需求一致性存在性）** Θ 与热状态空间紧、效用与热映射连续、获取收益次模 ⇒ TRC 存在不动点；F 压缩则唯一、阻尼迭代收敛。

## 7. 本轮最大风险

**一句话**：WARM-RAS 把安全性押在「热模型足够准、能预判余量」上——但**热是系统中最慢、最不可辨识、最容易被接触/对流/环境扰动的量**，一次模型失配就让系统误以为自己还有余量而去购买更多 VoI，而**热惯性意味着等观测器发现时，安全裕度已经被提前花掉**；**「精打细算地发热」可能比「根本不算」更危险，因为它给了系统一种有据可依的过度自信**。

**次级风险与缓解**：热模型失配（保形预测给余量保守下界 + COOL 优先）；需求过度追问/疲劳（CRU 决策相关门 + 提问预算）；需求投毒/策略性谎报（k 正交证据 + 行为一致性验证 + ℰ_req 对抗训练）；热攻击/计算 DoS（TCC 抗升级 + 异常热载检测 + 降级可预测）；热-需求一致性振荡（阻尼迭代 + 安全优先字典序）。
