# 第 8 轮 · METRO：视觉定位是最后一厘米，人形多视角是传感器，用户画像是恢复开关

> 检索/复核日期：**2026-10-25（UTC）**；承接第 7 轮 PILOT（2026-10-24 一手抓取）。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API。本轮灵感词是「视觉定位」「人形机器人」「用户画像」。
>
> **主判断**：第 7 轮把“终局放置”认成成功闸门是对的，但它只用了 2D 锚点和静态恢复库。真正缺的是三件事：**(1) 一个以容器/目标为中心、带不确定度的度量任务坐标系**（不是图像上的一个点）；**(2) 把 G1 的头戴双目 + 双腕 + 本体感知当成多视角度量系统**（不是把 G1 当“更高的桌面臂”）；**(3) 把实时人类干扰者建模成一个有意图的在线 agent**（官方备注是任务条件先验，现场人手/物体轨迹是似然）。三者合起来，才是“最后一厘米 + 20% 人为干扰”这两条最大杠杆的交点。

## 0. 本轮先核实：十个事实与修正

### 0.1 排名主指标是成功率，步骤分只是 tie-break（修正第 7 轮）

官方手册（中/英文）明确 [S8][S9]：

```text
主要指标：成功率得分
次要指标：步骤分得分
最终排名：总平均成功率 > 总平均步骤分 > 提交时间
每个任务 10 次真机执行；成功率 = 成功次数 / 10（保留两位小数）
每次执行即使未成功，也统计过程中完成的关键步骤，记为步骤分
```

第 7 轮把“放置类步骤约 59.7% 的步骤分占比”误读成“排名杠杆”，还把步骤分当成与成功率并列。**正确表述是：终局步骤仍是 32/32 任务的成功闸门；它的 39.8% 步骤分权重只在成功率打平时才影响排名。** 这不是文字修正，而是优化目标的修正：不要再为“多做一步部分分”设计主路径，要为“整条 episode 完整成功”设计主路径；步骤分只用于诊断失败位置和分配重试预算。

### 0.2 每任务 10 次 = 5 类泛化 × 2；人为干扰占 20%

官方 [S8][S9]：位置、干扰物、桌面背景、未见物品、人为干扰五类，每类各 2 次。**人为干扰不是边角料，是 20% 的计分试次**；而且由赛事方多名测试人员**实时布置/实时执行**，备注是剧本而不是精确回放。其余四类也由人工实时布置。位置泛化是“目标/容器初始位姿变化”，干扰物是“随机加杂物”，背景是“换桌布颜色/纹理”，未见物品是“同类但外观不同”。

### 0.3 每天只有 1 个测试时段；计分与不计分单任务共用额度

官方 [S8][S9]：**每支队伍每日仅可预约一个测试时段**；计分多任务与不计分单任务调试都须预约，管理员确认后占用排期；单任务调试不计入排行榜。第 7 轮“用调试槽做真机 A/B”的计划必须降级：**真机反馈是稀缺资源，单任务调试只做接口/pivot/安全 smoke test，主迭代靠离线与回放；计分跑是发布门，不是调参器。** 排行榜取多次计分评测中最好的一次；至少一次覆盖 32 任务且总步骤分 >0 才有资格。

### 0.4 提交 API 的真实观测键与数据集不同；右头相机可以声明

`unibot_submission` README [S11] 的实际键是：

```text
observation.images.cam_left_high   [480,640,3]
observation.images.cam_right_high  [480,640,3]
observation.images.cam_left_wrist  [480,640,3]
observation.images.cam_right_wrist [480,640,3]
observation.state.left_arm / right_arm [7]
observation.state.left_ee_pose_gripper_base / right_... [6]
observation.state.left_gripper / right_gripper [1]
observation.state.lower_body [15]   # 含 waist_yaw / waist_roll / waist_pitch
observation.language str
```

示例策略 `example_policy.py` 只声明了 `cam_left_high` + 双腕，**没有声明 `cam_right_high`**；但 API 支持它。要做头戴双目，必须显式声明右头相机，并在 `image_resize` / `obs_delta_indices` 里给它和左头相同的处理。`metadata` 的 `obs_delta_indices` 同时决定“传哪些键 + 每键堆叠几帧”；只声明模型真正消费的键，别把带宽浪费在没用的流上。

### 0.5 API 只暴露 `action.pivot[7]`；不能主动控制头/腰/躯干

动作目录 [S11]：共享键是 `action.left_gripper`、`action.right_gripper`、`action.pivot[7]`；二选一的是 `action.left_arm/right_arm[7]`（joint）或 `action.left_ee_pose_gripper_base/right_...[6]`（ee）。**没有** `action.waist_action_joint`、`action.action_torso`、`action.action_d435`——这些只存在于数据集。数据集里 `action.pivot` 的字段名是 `vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height`，HangCup/StackBowls 实测值恒为 `[0,0,0,0,0.15,0,0.74]`；`action.base_command` 是 `[0,0,0,0.74]`，`action.waist_action_joint` 是另外 3 维。也就是说：

- `pivot[0:3]` 与 `base_command[0:3]` 对齐（vx/vy/angle_z），`pivot[6]` 与 base height 0.74 对齐；`pivot[3:6]` 的语义未文档化（疑似腰/躯干，但值 `[0,0.15,0]` 与 waist 实测 `[-0.01,-0.004,0.18]` 对不上）。
- **不能假设可以主动转头/转腰/升降躯干**。主动视角只能退化为“base 小幅移动（若 pivot 前 3 维/height 真的生效）+ 手臂/腕部重定向”，且必须先在单任务调试里验证。
- 示例策略把 `action.pivot` 输出成全零；这是 stub，不是安全默认。**推理时应输出数据集默认 `[0,0,0,0,0.15,0,0.74]`，只在验证后小幅修改前 3 维/height。**

### 0.6 数据集有头戴双目标定与腕相机内参；这是被低估的度量信号

HangCup `meta/info.json` [S14] 的 `camera_params` 给出：

```text
  K_left  = [[282.369, 0, 311.525], [0, 282.752, 256.628], [0,0,1]]
```

`state_torso` / `state_d435` 在数据集里有（示例 episode 的 d435 在 torso 系约 `z=0.456 m, pitch=1.011 rad`），但**提交 API 不暴露这两个状态**；只能从 `lower_body` 的 waist 3 维 + URDF/标定先验去推头部/躯干位姿，或者干脆用“容器相对任务帧”让头部外参误差在相对变换中抵消。这是本轮最重要的工程判断之一。

### 0.7 评测编排：32 任务、N 机器人、N 端口、状态隔离、180 秒

官方 [S8][S9]：一次计分提交必须覆盖全部 32 任务；任务按**未事先通知的顺序**执行；任务随机分到 N 台 G1；每台机器人固定连一个端口，端口从 8765 起连续 `8765..8765+N-1`；每个端口的 `reset` 与历史状态严格隔离；服务需全程运行；单次运行限时 180 秒，超时记失败但已完成步骤分仍计入；平台会记录每步延迟与动作内容，异常/不规则交互会被核查。**这意味着：模型要跨机器人/跨工位稳健；per-port 状态不能串；动作要平滑、不能有 NaN/异常跳变；延迟要稳。**

### 0.8 排行榜仍是占位；29.7% 不是真实头部

`leaderboard.html` + `leaderboard_data.json` [S3][S4] 仍是 `generated_from=gen_leaderboard.py` 的 8 模型/256 条占位数据；`runs.html` 详情页明确写「测试视频占位」。榜首 MolmoAct2 29.7%/39.0、WALL-OSS-0.5 28.5%/38.9、DreamZero 27.9%/37.9……**这些数字不能当真实排名，也不能当真实天花板。** 可谨慎使用的只有两条弱先验：(a) 8 个模型“步骤分 − 成功率”平均约 +8.6pp，暗示失败多发生在后段；(b) 占位榜里反复靠后的任务是 Plug In Ethernet、Unlock、Pick Out Battery、Hang Cup、Stack Bowls、Zip Up 等，和“接触/闭合/悬挂/插入”一致。标“未核实”。

### 0.9 数据集 33,276 episodes / 18.28M frames / 约 169 小时

HF collection `unitreerobotics/unibot-v1-challenge-dataset` [S13] 实测（2026-10-25）：32 个数据集，`lerobot.totalEpisodes` 合计 **33,276**，datasets-server `numRows` 合计 **18,282,246** 帧，30fps，4 相机（头双 + 双腕），约 **169.3 小时**；collection `lastUpdated=2026-09-11`，HangCup `lastModified=2026-10-14`。官网挑战页写“32,000 episodes / 169 小时”[S2]——是约数。手册里的 `unibot-v1-challenge`（无 `-dataset`）是过期/错误链接；正确 slug 是 `unibot-v1-challenge-dataset`。

本轮通读中/英文手册可提取文本 [S8][S9]，只看到“同一模型完成所有任务、不得混合多个模型一起测试”“诚信参赛/赛后鼓励开源”“组委会保留规则修订权”；**没有**外部数据、仿真数据、预训练权重的明确条款。默认策略：**只用官方 33k；外部数据/仿真数据放在合规开关后；发邮件 `challenge_support@unitree.com` 确认。** 这不是技术判断，是合规风险。

## 1. 三个灵感词，各自钉到官方事实上

### 1.1 视觉定位：2D 锚点不够，必须是“度量任务坐标系”

第 7 轮的 PGL 是“槽位 → 2D 锚点渲染 → 6D 位姿”，锚点本质还是图像上的像素。对“放进/插进/叠上/挂上”这类终局，像素分辨率根本不够：

| 传感器 | 焦距/基线 | 工作距离 | 1 px 对应 | 16 px patch 对应 |
|---|---|---:|---:|---:|
| 头戴双目（全局） | f≈282 px, B=58.25 mm | 0.8 m | 2.83 mm | 45 mm |
| 头戴双目 | 同上 | 1.2 m | 4.25 mm | 68 mm |
| 腕部彩色（局部） | f≈436 px | 0.1 m | 0.23 mm | 3.7 mm |
| 腕部彩色 | 同上 | 0.2 m | 0.46 mm | 7.3 mm |

双目深度精度 `σ_Z ≈ Z²/(fB)·σ_d`：在 0.8 m、视差误差 0.1 px 时约 **3.9 mm**；0.5 m 时约 **1.5 mm**；1.2 m 时约 **8.8 mm**。**头戴双目足够估计容器/目标的全局位姿（厘米级），但不够插入/叠碗的最后一毫米；腕部相机 + EE 位姿才是最后一厘米的主传感器。** 这不是“二选一”，是分工：

- **表帧 `F_T`**：RANSAC 拟合桌面平面 + 重力方向 + 高度；给任务帧提供重力对齐和工作高度。
- **任务帧 `F_K`**：容器/端口/杯架/碗沿的 6D 位姿；由头戴双目点云 + 分割 + 几何拟合（平面/圆柱/矩形）或类别级 6D 位姿给出。
- **工具帧 `F_W`**：腕相机相对 EE 的手眼标定；由数据集腕相机内参 + EE 位姿离线标定，在线用腕部图像精化。
- **相对放置**：`T_B^EE* = T_B^K · H̄`，其中 `H̄` 是 K 条演示在容器系下的释放位姿稳健统计。**注意：头部外参的绝对误差在 `T_B^K` 和 `T_B^EE` 的同一个 base 系里会抵消；真正重要的是容器与 EE 的相对几何。** 这就是为什么“容器相对任务帧”比“绝对 3D 坐标”更适合本赛。
- **不确定度**：`Σ_G = Σ_K + Σ_H`；`Σ_G` 大 → 慢速/腕部伺服/换视角；`Σ_G` 小 → 直接执行。把“不确定性”显式化，才能决定何时用 2D 回退、何时重试。

证据方向：StereoVLA 在真机成功率上 +33.4% [P1]；ExStereo 把显式立体表示接进 2D VLA [P2]；FoveaVLA 用外部双目替代腕相机 [P3]；Active Stereo-Camera ACT 在 G1 上用单主动双目做到 87.5%/94.4% [P5]；CFVS 用 coarse-to-fine 6-DoF 视觉伺服做插孔 [P16]。**本轮的新意不是“用双目”本身，而是“用已标定的头戴双目 + 双腕 + 本体，构建容器相对任务帧 + 不确定度 + 变化检测”，并把 2D VLA 降为语义/粗规划层。**

### 1.2 人形机器人：不是“更高的桌面臂”，是“多视角 + 双手 + 可观测的腰”

G1 在本赛里的真正优势不是身高，而是：

- **头戴双目**：全局、稳定、带标定；看桌面、容器、人的手。
- **双腕相机**：局部、近距离、跟着手走；插入/叠碗/拉拉链的最后厘米。
- **双臂**：一手扶容器/插排/袋口，一手操作；双手相对帧让“扶”和“放”共享一个度量系。
- **腰/躯干**：`lower_body` 后 3 维是 waist_yaw/roll/pitch，**可观测但不可主动控制**（API 没有腰动作）；它决定了头/躯干的位姿，是头部外参估计的一部分。
- **base/height**：`pivot` 的前 3 维/height 可能可控，但未验证；只能作为条件性主动视角，不能当主路径。

**多视角融合**：头戴双目给 `T_B^K` 和人的手/物体；双腕给 `T_EE^obj` 和接触前的局部误差；本体给 `T_B^EE` 和自遮挡 mask。三者用因子图/卡尔曼滤波融合，输出一个带协方差的 `T_B^K`。**双手相对帧**：如果左臂扶住插排/容器，右臂的目标不再是 base 系的绝对位姿，而是 `T_L^R* = T_L^K · H̄_R`；`T_B^R* = T_B^L · T_L^R*`。这直接把“双手协调”从“学一个双手机器人策略”变成“一个相对位姿 + 一个单臂伺服”，样本效率和控制精度都更好。

证据方向：ActiveMimic 用 G1 类人形的 2-DoF 头 + 2-DoF 腰做主动感知 [P7]；SaPaVe 用 G1 + 主动头相机做主动操作 [P6]；Compositional Humanoid Manipulation 展示人形双臂组合操作 [P15]；VLBiMan 研究动态干扰下的双臂操作 [P10]。**本赛的 API 不给我们主动头/腰，所以“人形”要落在“多视角融合 + 双手相对帧 + 可观测腰”上，而不是“主动转头”。**

### 1.3 用户画像：把实时干扰者建模成“有意图的在线 agent”

“用户画像”在这里不是给测试员做身份画像，而是**对评测现场的人类干扰者做意图/行为画像**：

- **先验**：每个任务的 `generalization.human_1_note` / `human_4_note` 是官方公开的干扰剧本 [S6]。例如 T27「把粉色碗向下移动」「叠了第二个之后拿下第二个」；T19「把包向左边移动」「拉上拉链之后拉开」；T14「拧开盖子之后拧动回来」；T10「将插头拔起」。这些备注给出了**对象、动作、方向、时机（某步之前/之后）**。离线把 32×2 条备注解析成结构化 JSON：`{task, object, action, direction, trigger_step, timing}`，作为任务条件先验 `P(g|task)`。
- **似然**：头戴双目做背景建模 + 运动分割，检测人的手/手臂/被移动物体；用 3D 轨迹、手-物距离、物体位移、与机器人自身运动的排除，计算 `P(z|g)`。
- **后验**：`P(g|z_{1:t}, task) ∝ P(z_{1:t}|g) P(g|task)`；`g ∈ {none, observe, move_target, move_container, undo_step, add_distractor, occlude, take_object}`。`risk = Σ_{g∈G_risk} P(g|...)`。
- **门控**：`risk` 高且人在工作空间内 → 选择 `wait / shield(退让/抬臂) / re-localize / rollback / retry`；`risk` 低 → 继续。等待预算（例如每次 ≤5 s、整集 ≤20 s）防止被“假阳性”拖死 180 s。
- **恢复**：如果人把已完成步骤撤销（T27 拿走第二个碗、T19 拉开拉链、T14 拧回瓶盖），SSG 把步骤回退，MCF 触发重定位，NRB 用官方备注的“破坏→恢复”对做监督；如果人把目标移走/拿走，重定位后重新规划；如果人只是加干扰物/遮挡，继续或换腕部视角。

证据方向：HINT 用人类意图 inception 做长程操作 [P8]；EgoRecovery 从人类恢复演示学失败恢复门控 [P9]；VLBiMan 研究动态干扰下的双臂鲁棒性 [P10]。**本赛的独特点在于：官方备注是“任务条件先验”，不是训练集里的一条随机扰动；这把“人类干扰”从 20% 的运气题，变成 20% 的可推断题。**

**备选解释**（保留但不当主路径）：(a) **测试员/场景画像**——从场景统计推断当前泛化轴（背景变了/多了杂物/目标换了/有人在旁边），调整检索簇和谨慎级别；(b) **演示者风格画像**——离线聚类 33k 演示的操作风格（速度/接近方向/抓取点），给策略一个 style token，处理多模态演示。两者都不采集身份，只做场景/动作统计。

## 2. 评分算术：为什么是“最后一厘米 + 干扰恢复”两条最大杠杆

### 2.1 主指标分解

```text
overall = (1/32) Σ_t (1/10) Σ_r success_{t,r}
success = ∧_k predicate_k          # 终局步骤是每任务的闸门
step_score = Σ_k w_k · predicate_k # 诊断/ tie-break，不是主目标
```

### 2.2 增益近似

| 改进 | 作用范围 | 总成功率增益近似 |
|---|---|---|
| 所有任务终端成功率 +Δ_t | 32/32 任务 | ≈ q·Δ_t（q=到达终局步的概率，估 0.5–0.7） |
| 人为干扰试次恢复 +Δ_h | 2/10 试次 = 20% | ≈ 0.2·Δ_h |
| 8 个高难任务 +Δ_s | 8/32 = 25% | ≈ 0.25·Δ_s |
| 单轴泛化 +Δ | 1/5 试次 | ≈ 0.2·Δ |

**示例**（乐观、可能重叠）：q=0.6、Δ_t=5pp → +3.0pp；Δ_h=15pp → +3.0pp；Δ_s=10pp → +2.5pp；合计约 +8.5pp。保守目标 +4–6pp；冲刺 +8–10pp。对照占位榜首 29.7%，+5pp 就是 34.7%，已是明显跃迁。

### 2.3 统计噪声与提交策略

320 个计分 episode、p≈0.3 时二项 SE≈2.56pp；任务间难度差异还会放大有效 SE。排行榜取多次计分评测的最好一次，**“一次运气 +10pp”不如“三次稳定 +5pp”**。建议 3–5 次计分跑；每次只改一个主变量；用 per-task 10 次明细做配对诊断，而不是只看总分。

### 3.5 为什么不是“再堆一个 2D VLA”

- **语义不是瓶颈**：32 个任务的指令/物体类别很清楚；占位榜的难点集中在插入、悬挂、叠碗、拉拉链、开锁——接触/闭合/精度，不是“不认识杯子”。
- **2D token 的度量分辨率不够**：头相机 16 px patch 在 0.8 m 约 45 mm；插入/叠碗的容差远小于此。VLA 可以做“往哪放”的粗规划，但最后一厘米必须由腕部像素级伺服/几何闭环接管。
- **20% 试次是人**：演示数据里没有“人手伸进来把碗拿走”的分布；再多的成功演示也不会自动长出恢复策略。官方备注是免费的任务条件先验，不用白不用。
- **立体信号已经在机器人上**：头戴双目已标定、已同步、已进数据集；不用它，相当于把 G1 最值钱的传感器降级成两个单目。

## 4. 风险与合规（先立后破）

- **透明/反光/薄物体**：试管、拉链、毛巾、塑料袋的立体匹配会失效 → 腕部单目 + 2D 关键点 + 几何先验 + 柔顺/螺旋搜索；SML 置信度低时回退到 2D VLA/OPT，不硬做 6D。
- **头部外参/标定**：API 不给 `state_d435`/`state_torso`；靠 `lower_body` waist + URDF/数据集标定先验；用“容器相对任务帧”让绝对外参误差在相对变换中抵消；Station Profile 每端口用桌面平面/物体尺寸复核。
- **人体检测被机器人自遮挡/自运动干扰**：用 FK 渲染机器人 mask、深度/运动分割、双腕视角融合；先在实验室采 2–3 小时“人伸手移动物体”数据验证，再上真机。
- **HIP 假阳性**：等待/退让会吃 180 s 预算；用代价敏感阈值 + 等待预算 + “只在高风险时覆盖”的保守门控；假阳性高就退化为“只等待、不回滚”。
- **单模型合规**：所有任务必须同一模型，不得混合多个模型。方案是**一个 checkpoint（VLA + 轻量度量/分割头）+ 确定性几何代码**；SGBM/平面拟合/因子图不算“模型”；若用 Fast-FoundationStereo/SAM 等现成网络，要么蒸馏进 checkpoint，要么在模型卡里披露并邮件确认。
- **延迟**：4 路 480×640 + 立体 + 点云 + VLA，容易把 p99 拉高；用 SGBM/经典立体、10 Hz 感知、3–5 Hz VLA + 8–16 步 chunk、异步线程；目标 `get_action` p99 <100 ms；平台会记录延迟/动作规律性。
- **每天 1 槽**：真机反馈稀缺；单任务调试只做接口/pivot/安全 smoke test；主迭代靠离线/回放；计分跑 3–5 次，每次一个主变量。
- **占位榜单**：29.7% 不是真实天花板；不要把占位任务的难度排序当训练目标；等真实榜单发布后再做 per-task 诊断。
- **外部数据**：手册未明文允许/禁止；默认只用官方 33k；外部数据/仿真数据放合规开关后；邮件确认。
- **pivot 语义**：`pivot[3:6]` 未知；不要假设能主动转腰/转头；输出数据集默认值；在单任务调试里做小幅阶跃测试，确认方向/单位/安全范围后再用。
- **任务顺序保密/跨机器人**：不要做任务特定的“作弊”分支；用单一模型 + Station Profile + 稳健归一化；动作要平滑，避免被平台判为异常。

## 5. 一句话押注

**把 G1 的头戴双目 + 双腕 + 本体感知做成以容器/目标为中心的度量任务坐标系（SML），把官方人类干扰备注做成在线意图先验（HIP），再用任务帧位姿迁移（OPT）+ 腕部视觉伺服（VS）+ 双手相对帧（BRF）打最后一厘米；在“成功率主指标、20% 人为干扰、每天 1 槽”的真实约束下，这比再堆一个 2D VLA 更可能把 32 个任务的终端成功率抬起来。**

## 1. 事实核对（全部一手；来源表见 §12）

### 1.1 评分与排名（官方手册，中/英）

官方原文 [S8][S9]：

```text
主要指标：成功率得分
次要指标：步骤分得分
最终排名：总平均成功率 > 总平均步骤分 > 提交时间
每个任务 10 次真机执行；成功率 = 成功次数 / 10（保留两位小数）
每次执行即使未成功，也统计过程中完成的关键步骤，记为步骤分
单次运行最大 180 秒；超时记为失败，并根据执行情况计算步骤分
```

**关键推论**：32 个任务的成功率平均是主指标；步骤分是 tie-break + 诊断。终局步骤是每任务的**成功闸门**（所有步骤完成才算成功），但它的步骤分权重（32 任务合计 1275/3200 = 39.8%）不是排名权重。第 7 轮把这两件事混了，本轮修正。

### 1.2 评测编排（官方手册）

- 一次计分提交必须覆盖全部 **32 个任务**；系统按**未事先通知的顺序**执行。
- 任务随机分配到 **N 台 G1**；每台机器人固定一个端口，端口从 **8765** 起连续 `8765..8765+N-1`；每端口独立进程/共享后端均可，但必须能并发、不能相互阻塞。
- 每端口对应独立机器人的独立任务；**`reset` 与历史状态严格隔离**，不可串用。
- **同一任务的 10 次泛化场景在同一台真机上评测**；不同任务在每次测评中随机分布到各台机器人；同一泛化场景在多次测试中也可能分到不同机器人（不保证连续同一台）。

**动作** [S11]：

| 键 | 形状 | 控制空间 | 说明 |
|---|---|---|---|
| `meta.token` | str | shared | 每步返回，双处校验 |

| `action.left_arm/right_arm` | [7] | joint | 目标关节 |
| `action.left_ee_pose_gripper_base/right_...` | [6] | ee | 目标 EE 位姿 |

**元数据**：`control_space`（joint/ee 互斥）、`obs_delta_indices`（选哪些键 + 每键堆叠帧）、`image_resize`（每图目标分辨率）、`action_chunk_size`（≥1）、`token`。`reset()` 每 episode 一次。`observation.language` 的时间偏移必须是 `[0]`。

**实践要点**：

- 要做双目，必须显式声明 `cam_right_high`；否则只有单目。
- `image_resize` 会先在评测端缩放再发；头双目为了深度精度尽量保 480×640 或至少 320×480；双腕可 320×320/480×640，按延迟实测。
- `obs_delta_indices` 只声明模型真正消费的键；不用的流不要传。
- 示例策略的 `action.pivot` 全零是 stub；推理应输出数据集默认 `[0,0,0,0,0.15,0,0.74]`，再在验证后小幅修改。
- `action_chunk_size` 是延迟/平滑的旋钮：8–16 步 chunk 可把 VLA 频率降到 3–5 Hz；但 chunk 太长会牺牲反应性，尤其 HIP 门控需要快速中断。

## 2. 头部方案分析（在占位数据约束下）

### 2.1 先说清楚：现在没有“真实头部方案”

榜单是占位数据，详情页视频也是占位；所以**不能**说“榜首用了什么、瓶颈是什么”。能做的只有两件事：

1. 分析榜单点名的**模型家族**的公开架构与架构性瓶颈；
2. 用占位榜的**任务难度模式**做弱先验（标“未核实”）。

### 2.2 模型家族的做法与瓶颈

| 模型 | 公开架构（据公开资料） | 强项 | 架构性瓶颈 | 我们借/不借 |
|---|---|---|---|---|
| **MolmoAct 2** | VLM + action reasoning + flow-matching action expert；2D 轨迹 token [P11][P12] | 语义/语言 grounding、2D 空间推理、可解释 | 2D 轨迹不带度量深度；插入/叠碗的最后厘米靠隐式；大 VLM 延迟 | 借“2D 粗规划/动作推理”；不借“2D 轨迹当最终控制” |
| **DreamZero** | 14B world action model；视频扩散；约 7 Hz [P13] | 物理动态、长程预测、零样本 | 重、慢；接触-rich 精度；世界模型幻觉 | 不借在线主路径；可离线做数据增强/评估 |
| **π0.5** | 开放世界 VLA；2D RGB + 语言 → action（公开资料） | 语义泛化、开放物体 | 无显式度量 3D；精密放置/插入弱 | 借语义 backbone 思路；加 SML/VS |
| **GR00T N1.5** | 人形 VLA；双臂；2D RGB [见公开资料] | 人形数据、双臂协调 | 精密接触、人类干扰恢复；无显式立体 | 借人形/双臂配方；加 BRF/HIP |
| **WALL-OSS-0.5** | 开源具身基础模型（公开细节有限） | 开放生态 | 数据覆盖、精密任务 | 只做对比基线 |
| **Spirit-v1.5 / DM0 / GigaBrain-0** | 公开细节有限；大概率 2D VLA/world-model 变体 | 各自数据/模型规模 | 数据覆盖、接触、恢复 | 不 overclaim；等真实榜单 |

> 注：π0.5、GR00T N1.5 的引用在本轮检索材料中没有稳定的一手论文链接，故不编造 URL；只按公开模型家族做架构性分析。MolmoAct/DreamZero 有一手链接 [P11]–[P13]。

### 2.3 共同盲区（这就是我们的机会）

1. **2D RGB → action**：没有显式度量深度/任务帧；插入、叠碗、挂杯、拉拉链的容差远小于 2D patch 分辨率。
2. **静态任务帧**：假设物体不动；人被移动目标/容器后，策略没有“任务帧失效”的概念，继续按旧轨迹执行。
3. **成功演示偏置**：33k 演示几乎都是成功轨迹；没有“人手伸进来拿走碗/拉开拉链/拔掉插头”的恢复分布。
4. **人类干扰被当噪声**：没有把官方备注当先验；20% 的计分试次靠运气。
5. **重模型/低频率**：world model/VLA 很大，30Hz 控制靠 chunk 摊销；接触前反应慢。
6. **双臂协调隐式**：没有“扶/操作”相对帧；双臂碰撞/分工靠数据硬学。
7. **跨工位差异**：N 台机器人、不同相机/桌面/夹爪；没有 per-port 标定层。

### 2.4 为什么占位榜首也只有 29.7%（如果这个结构在真实榜单里成立）

- **任务语义简单**：32 个任务的物体/指令都很清楚，失败不在“不认识杯子”，而在“最后一下没对准/没插进/没叠稳/被人拿走”。
- **2D VLA 的训练目标**：主要是成功轨迹的 action likelihood；没有显式度量深度、没有任务帧失效、没有恢复负样本。
- **20% 人为干扰在演示分布外**：模型没有“等人/回滚/重定位”的概念，遇到人手只能继续按旧轨迹走。
- **N 台机器人/工位差异**：没有 per-port 标定，相机/桌面/夹爪差异放大方差。
- 所以 29.7% 更像是“架构缺少度量与恢复”，而不是“模型不够大”。这三件事恰好对应 METRO 的 SML / HIP / Station Profile。

### 2.5 我们借什么、不借什么

- **借**：MolmoAct 的 2D 动作推理/粗规划；GR00T 的人形/双臂数据配方；π0.5 的开放语义；DreamZero 的离线动态评估；Active Stereo/Visual Servoing 的几何闭环 [P1]–[P7][P16]。
- **不借**：14B world model 在线主路径；纯 2D 轨迹 token 做最后厘米；每任务一个策略；全 32 任务高保真孪生；外部数据默认开启。
- **差异化**：**度量任务帧 + 官方备注先验 + 双手相对帧 + 变化检测回滚**。这不是“再做一个 VLA”，而是“给 VLA 装上度量与恢复的外骨骼”。

## 3. 评分算术与目标

### 3.1 主指标分解

```text
overall = (1/32) Σ_t (1/10) Σ_r success_{t,r}
success = ∧_k predicate_k          # 终局步骤是每任务闸门
step_score = Σ_k w_k · predicate_k # 诊断/tie-break
```

### 3.2 两条最大杠杆

| 改进 | 作用范围 | 增益近似 |
|---|---|---|
| 所有任务终端 +Δ_t | 32/32 | q·Δ_t（q≈0.5–0.7） |
| 人为干扰恢复 +Δ_h | 2/10 = 20% | 0.2·Δ_h |
| 8 个高难任务 +Δ_s | 8/32 = 25% | 0.25·Δ_s |
| 单轴泛化 +Δ | 1/5 = 20% | 0.2·Δ |

**算例**：q=0.6、Δ_t=5pp → +3.0pp；Δ_h=15pp → +3.0pp；Δ_s=10pp → +2.5pp；合计约 +8.5pp（乐观、可能重叠）。保守目标 +4–6pp；冲刺 +8–10pp。

### 3.3 统计噪声与提交策略

- 320 个计分 episode、p≈0.3：二项 SE≈2.56pp；任务间难度差异会放大有效 SE。
- 排行榜取多次最好；**“一次运气 +10pp”不如“三次稳定 +5pp”**。
- 建议 3–5 次计分跑；每次只改一个主变量；用 per-task 10 次明细做配对诊断，不只看总分。
- 占位榜的 +8.6pp 步骤分—成功率差只能当“失败多在后段”的弱先验，不能当模型能力。

### 3.4 预算分配（修订第 7 轮）

```text
SML/OPT/VS（最后一厘米）        40%
HIP/MCF（干扰与恢复）           25%
数据/标注/回放（TLE/ACP/GF）    20%
部署/延迟/工位标定              15%
```

```text
Online（单一 checkpoint + 确定性几何）
  obs（4 图 + proprio + language）
    ├─ SML：立体深度 → 点云 → 表帧/任务帧/工具帧 → T_B^K, Σ_K
    ├─ MCF：物体位姿/点云变化检测 → 人/机器人归因 → 任务帧失效
    ├─ SSG：指令→任务→步骤图；谓词/成功门控；回退
    ├─ HIP：人手/物体跟踪 + 备注先验 → 意图后验/风险
    ├─ GPR-VLA：4 视图 + 度量 token + 意图 token + 检索上下文 → 动作 chunk
    ├─ VS：腕部伺服 → 缓放 → settle-verify → nudge/regrasp/retry
    ├─ BRF：扶/操作双臂相对帧 → 单臂相对目标
    └─ action chunk（shared + joint/ee）
```

### 4.2 SML：立体度量定位

**输入**：`cam_left_high`、`cam_right_high`、双腕、`lower_body`（含 waist）、EE 位姿、夹爪、语言。

**步骤**：

1. **整流/校正**：用数据集头双目 `K/R/T` 对左右图做 rectify；若 API 图已整流，跳过但保留标定。
2. **视差/深度**：优先 OpenCV SGBM/BM + WLS 滤波（确定性、低延迟、无“多模型”合规问题）；低纹理/透明失败时回退到腕部单目 + 2D 关键点。Fast-FoundationStereo 只作为离线教师/备选 [P4]。
3. **点云**：`P_C = Z K^{-1}[u,v,1]^T`；用 waist/URDF 或标定先验把 `P_C` 变到 base 系（`T_B^C`）。
4. **表帧**：RANSAC 平面 + 法向/高度；`T_B^T`（重力对齐、工作高度）。
5. **任务帧**：按任务选择几何模型：
   - 杯/碗/瓶/试管：圆柱拟合（轴/半径/中心）。
   - 杯架/碗沿/插排/端口：平面/矩形/边缘 + 关键点。
   - 袋子/拉链/毛巾：2D 关键点/边缘 + 可变形先验（不做硬 6D）。
   - 未见物体：点云 PCA + 尺寸先验 + 抓取点检测。
6. **工具帧**：腕相机-EE 手眼标定（离线用数据集腕图 + EE 位姿；在线用腕部图像/已知物体尺寸精化）。
7. **融合**：因子图/卡尔曼滤波，输出 `T_B^K` 与 `Σ_K`。
8. **相对化**：不追求绝对 world 坐标；所有放置/插入目标都在任务帧里表达。

**为什么相对化能抵消头部外参误差**：`T_B^EE* = T_B^K · H̄`。`T_B^K` 和 `T_B^EE` 共享同一个 base 系；头部外参的同一偏移会同时作用在“看到的容器”和“要去的 EE 目标”上，在相对量里抵消。真正需要准的是**容器与 EE 的相对几何**，由腕部相机/EE 链保证。

### 4.3 MCF：度量一致性滤波与变化检测

- **状态**：任务帧 `T_B^K`、物体位姿、容器位姿、人手/物体轨迹。
- **变化检测**：`Δ_t = ||T_B^K(t) - T_B^K(t-1)||_Σ`；若 `Δ_t > τ`，且机器人夹爪不在该物体附近/不是机器人造成 → 标记“外部变化”。
- **归因**：用 EE 位姿/夹爪开度/FK 渲染机器人 mask，排除自运动；剩余运动聚类 → 人手/物体。
- **后果**：
  - 目标/容器被移动 → 任务帧失效 → 重定位/重规划。
  - 已完成步骤被撤销 → SSG 回退 → NRB 恢复。
  - 只是干扰物/遮挡 → 继续/换腕部视角。
- **输出**：`change_flag`、`changed_object`、`cause`（human/robot/unknown）、`recommended_action`。

### 4.4 SSG：评分步骤图与成功门控

- **输入**：`info.json` 的 `score_steps` + 5 条复述 + 中文描述 [S6]。
- **图**：每个任务一个**偏序图**（不是严格线性）：节点=步骤，边=前置条件；权重 w_i；终局节点=成功门控。
- **指令匹配**：32×5=160 条复述 + 中文映射；精确/规范化/嵌入兜底。
- **谓词**：几何关系（距离/朝向/包含/接触/闭合）+ 事件（抓/放/插/拔/拧/拉）。
- **运行**：只有谓词确认才前进；未确认 → 重试/回退；人撤销 → 回退。
- **用途**：成功门控（主）、失败诊断（步骤分）、重试预算分配、HIP 的“被影响步骤”定位。
- **注意**：不要把步骤分当主目标；SSG 的价值是“知道现在该做什么/是否真的成功”，不是“多刷部分分”。

### 4.5 OPT：任务帧放置位姿迁移

- **离线**：对任务 t 的每条演示 i，估计容器系 `T_B^K_i`（标定 + 6D/关键点），取释放时刻 EE 位姿 `T_B^EE_i(t_rel)`：

```text
H_i = (T_B^K_i)^{-1} · T_B^EE_i(t_rel)
```

- **线上**：估计 `T_B^K`；检索 K 条行为对齐演示（ICR 键）；稳健统计：

```text
H̄.xyz = median_i(H_i.xyz)
H̄.rot = quaternion chordal mean
T_B^EE* = T_B^K · H̄
Σ_G = Σ_K + Σ_H
```

- **决策**：

```text
Σ_G 小        → 直接执行
Σ_G 中        → 慢速 + 腕部伺服
Σ_G 大        → 放弃迁移 → 2D 锚点/保守放置
τ_task        ← 同任务演示 H_i 的 95 分位差（叠碗大、插头小）
```

- **为什么是“少样本”**：迁移的是 K 条演示的**相对位姿统计**，不是复制轨迹；零梯度、可缓存、跨外观/背景/位置。
- **与第 7 轮的区别**：PGL 的 2D 锚点降为可视化/回退；主路径是 6D 任务帧 + 协方差。

### 4.6 VS：腕部视觉伺服与 settle-verify

```python
def place_and_verify(step, obs, plan, budget=2):
    for attempt in range(budget + 1):
        target = SML.task_frame(step, obs)          # T_B^K, Σ_K
        ctx    = ICR.retrieve(step, obs, k=4)
        for chunk in stream(policy.act(obs, target, ctx, s=step)):
            send(chunk)                              # 30Hz / chunk
            if predicate_met(step, obs):             # 粗谓词
                break
        if not predicate_met(step, obs):
            plan = revise(plan, obs, reason=diagnose(step, obs)); continue
        # 最后一厘米：腕部单目/几何伺服
        for _ in range(servo_steps):
            err = wrist_error(step, obs)             # 端口/碗沿/拉链/杯柄
            if norm(err) < eps: break
            send(servo_action(err))                  # 小步、限速
        open_gripper(slow=True); sleep(0.5)
        if stable(step, obs, window=0.5):            # 位移<eps 且谓词保持
            return True
        if repairable(step, obs):
            plan = nudge_plan(step, obs)             # 推正/轻压
        else:
            regrasp(step)
    return False
```

- `stable`：物体相对位姿 0.5s 内位移 <ε（由演示统计给出）+ 谓词保持。
- `predicate_met`：SSG 谓词 + 事件（接触/静止）。
- 预算：普通任务 ≤2 次；长程任务（T16/T17/T31）≤1 次；总时长守卫兜底。

### 4.7 HIP：人类干扰者画像与恢复门控

**先验**：官方备注 JSON（§1.6）。**似然**：头双目背景建模 + 运动分割 + 手/物跟踪。

```text
g ∈ {none, observe, move_target, move_container, undo_step,
     add_distractor, occlude, take_object}
P(g | z_{1:t}, task) ∝ P(z_{1:t} | g) P(g | task)
risk = Σ_{g ∈ G_risk} P(g | ...)
```

**特征**：人手/物体 3D 位置/速度、手-物距离、物体位移、与机器人 EE 的距离、任务步骤、备注先验、时间。

**门控**：

| 意图 | 风险 | 动作 |
|---|---|---|
| move_target / move_container | 高 | 暂停/退让，等人手离开，重定位，重规划 |
| undo_step | 高 | SSG 回退，等人完成，NRB 恢复 |
| take_object | 高 | 判断是否关键；关键则等待/重试，非关键继续 |
| occlude | 中 | 换腕部视角/小幅 base 退让/等待 |
| add_distractor | 低 | 忽略，继续 |
| none/observe | 低 | 继续 |

**预算**：每次等待 ≤5s，整集 ≤20s；假阳性高 → 只等待、不回滚。

**为什么用官方备注**：备注给出对象/动作/方向/时机，把“人类干扰”从随机扰动变成**任务条件先验**；现场轨迹只负责更新后验。这是本报告最独特的“用户画像”用法。

**伦理/合规**：不采集人脸/身份/生物特征；只用手/物体轨迹；episode 结束丢弃；不做跨 episode 个人化；目的是安全与恢复。

### 4.8 BRF：双手相对帧

- 任务图决定“扶”/“操作”分工（例如 T10 左手扶插排、右手插插头；T18 左手扶袋、右手拉拉链）。
- 扶的手臂提供 `T_B^L`（EE/夹持物）；操作臂目标：

```text
T_L^R* = T_L^K · H̄_R
T_B^R* = T_B^L · T_L^R*
```

- 若没有扶的任务，退化为任务帧/表帧。
- 好处：相对位姿减少 base/头部外参误差；双臂共享一个度量系；碰撞检查在相对空间更容易。
- 风险：双臂碰撞/工作空间限制；用关节限位/碰撞球/速度限幅兜底。

### 4.9 AVS-lite：base/arm 视角调整（条件性）

- API 不给头/腰动作；只能尝试 `pivot` 前 3 维/height（base 小幅移动）或手臂/腕部重定向。
- 触发：立体置信度低、目标被遮挡、对称歧义、HIP 说“人正在遮挡”。
- 动作：小幅后退/侧移/升降（若 pivot 验证有效），或抬腕/转腕；幅度 ≤5cm/5°，时间 ≤2s。
- 失败回退：不调整，直接等待/重定位/2D 回退。
- **状态：条件性，不配当主投注。** 先在单任务调试里验证 pivot 方向/单位/安全范围。

### 4.10 ICR：度量检索条件化

- **库**：33k → 任务×步骤相位切段（抓取段、终局段、闭合/插入段），每段 1–2s；约 26 万段。
- **键**：指令复述嵌入；相位；目标/容器关键点相对位移/朝向；容器相对底座；最近 1s 光流/EE 速度；**SML 的任务帧几何特征**（容器类型/尺寸/位姿）。
- **值**：缓存上下文编码（离线预编码）+ 动作先验（K 段动作稳健均值，作为初始化/残差锚）。
- **注入**：上下文 token（长度有界）+ 动作先验小权重融合。
- **延迟**：HNSW <5ms；编码离线；目标 p99 <100ms。

### 4.11 GPR-VLA：单一 checkpoint

- **底座**：WLA-1.0-Base/GPR-VLA（第 7 轮选定），LoRA + action expert。
- **输入**：4 视图（头双目 + 双腕）、proprio、语言、**度量 token**（`T_B^T`、`T_T^K`、`T_B^EE`、`T_EE^W`、`Σ_K`、物体 ID/类型）、**意图 token**（人手位置/速度、`P(g)`、`risk`）、ICR 上下文。
- **输出**：动作 chunk（EE 或 joint）、夹爪、pivot 默认；辅助头：任务帧位姿、步骤谓词、变化 flag、意图分类、放置目标。
- **合规**：唯一学习主干；SML/MCF/SSG/BRF 是确定性几何/代码；分割/位姿头若学习，作为同一 checkpoint 的辅助头；现成网络（SAM/FoundationPose/Fast-FoundationStereo）只做离线教师或蒸馏，不进在线多模型堆叠。

### 4.12 Station Profile：每端口标定

- 每个端口/工位在 reset 后估计：桌面平面/高度、头相机-底座关系（用 waist FK/标定先验）、腕相机-EE 手眼、夹爪偏置、链路延迟。
- 只保留**静态标定**，不保留 episode 历史；`reset` 清 episode 状态。
- 作用：吸收 N 台机器人/相机/桌面差异；减少跨工位方差；给 SML 一个可信初值。
- 风险：不要把“跨 episode 画像”做成状态泄漏；如需持久化，只存标定参数，并披露。

### 4.13 部署与延迟

- **拓扑**：N 端口 → 共享推理后端（请求分发）或每端口独立进程；状态隔离；并发队列；超时/健康检查。
- **频率**：感知 10 Hz；VLA 3–5 Hz + 8–16 步 chunk；腕部伺服 30 Hz（轻量控制循环）；HIP 门控 10–30 Hz（轻量检测）。
- **目标**：`get_action` p99 <100 ms；动作平滑、无 NaN/异常跳变；延迟稳定（平台会核查）。
- **降级**：立体失败 → 2D/腕部；VLA 超时 → 返回上一 chunk 的安全子段/保持；HIP 假阳性 → 只等待；网络抖动 → 缓存/重试。
- **安全**：速度/加速度限幅；工作空间边界；人靠近时降速/停止；不往人手方向快速运动。

## 5. 关键算法

### 5.1 立体深度与点云

```text
d = u_L - u_R
Z = f · B / d
P_C = Z · K^{-1} · [u, v, 1]^T
σ_Z ≈ Z² / (f · B) · σ_d
```

数值（HangCup 标定）：`f≈282.37 px`，`B=58.25 mm`；`σ_d=0.1 px` 时：

| Z | 1 px 横向 | σ_Z（0.1 px 视差） |
|---:|---:|---:|
| 0.5 m | 1.77 mm | 1.5 mm |
| 0.8 m | 2.83 mm | 3.9 mm |
| 1.2 m | 4.25 mm | 8.8 mm |

腕部：`f≈436.4 px`；0.1 m 时 1 px≈0.23 mm；0.2 m 时≈0.46 mm。**头双目做全局任务帧；腕部做最后厘米。**

### 5.2 表帧/任务帧

```text
表帧：RANSAC 平面 n_B·x + d = 0；z_T = n_B；x_T/y_T 由重力/机器人朝向定
任务帧：T_B^K = [R_K | t_K]；R_K 由容器轴/端口法向/杯架平面定
工具帧：T_EE^W（手眼）；T_B^W = T_B^EE · T_EE^W
```

### 5.3 因子图与不确定度

```text
节点：T_B^T, T_T^K, T_B^EE, T_EE^W
因子：
  f_plane(T_B^T; P_head)                  # 点到平面
  f_obj(T_T^K; P_head, mask)              # 点到模型/PnP
  f_wrist(T_T^K; I_wrist, T_B^EE, T_EE^W) # 重投影
  f_proprio(T_B^EE; q)                    # FK
  f_smooth(T(t), T(t-1))                  # 时序
求解：Gauss-Newton / GTSAM；输出 T_B^K, Σ_K
```

```text
Σ_K = (J^T Ω J)^{-1}
Σ_G = Σ_K + Σ_H
```

### 5.4 放置位姿迁移

```text
H_i = (T_B^K_i)^{-1} · T_B^EE_i(t_rel)
H̄ = robust_mean({H_i})       # xyz median + quaternion chordal mean
T_B^EE* = T_B^K · H̄
```

### 5.5 视觉伺服

```text
e = [u* - u, v* - v, log(R* R^T)]
Δx = -λ · J_w^+ · e
```

- 粗对齐 XY → 朝向 → Z 插入；柔顺/螺旋搜索兜底。
- 插入/叠碗的 `e` 由腕部图像（端口边缘/碗沿/杯柄）算；头双目只给任务帧。

### 5.6 人类意图后验

```text
P(g | z_{1:t}, task) ∝ P(z_{1:t} | g) · P(g | task)
risk = Σ_{g ∈ G_risk} P(g | ...)
```

- `P(g|task)`：官方备注解析出的软先验（命中对象/动作/时机 → 高；其余均匀）。
- `P(z|g)`：手-物距离、物体位移方向、速度、与任务步骤的时序。
- 分类器：规则 + 逻辑回归/小 GRU；先用可解释规则，再用实验室数据训练。

### 5.7 变化检测与回滚

```text
Δ_t = || T_B^K(t) - T_B^K(t-1) ||_Σ
if Δ_t > τ and not robot_caused:
    flag external_change
    if affected completed step: SSG.rollback(step)
    else: re-localize / replan
```

### 5.8 双手相对帧

```text
T_L^R* = T_L^K · H̄_R
T_B^R* = T_B^L · T_L^R*
```

### 5.9 成功谓词与重试

```text
pred_k = 1[dist(T_B^obj, T_B^target) < τ_k] ∧ event_k
success = ∧_k pred_k
step_score = Σ_k w_k · pred_k
```

- `τ_k` 由同任务演示的 95 分位差给出（叠碗大、插头小）。
- 重试预算：普通 ≤2；长程 ≤1；总时长守卫。

## 6. 数据引擎

### 6.1 官方 33k 的用法

- **全部 32 任务**；4 相机；30fps；EE base/torso 位姿；5 复述；`score_steps`；`generalization` 备注。
- **训练**：GPR-VLA 主训练 + SML 辅助头 + HIP 先验/分类器。
- **标注**：TLE 相位/谓词/接触；SML 容器/目标 6D/关键点；OPT 释放位姿。
- **验证**：按任务/难度/泛化轴分桶；留出 episode 做离线评估。

### 6.2 离线标注

- **自动**：用现成分割/6D（SAM 2/Grounded-SAM 2/FoundationPose）离线生成掩码/位姿，人工抽检；**只做教师，不进在线多模型**。
- **半自动**：容器/端口/杯架用几何拟合；用演示的 EE 释放位姿反推容器系，交叉验证。
- **人工**：每任务 20–50 条 episode 的关键帧（抓/放/插/闭合）做 QA；总计约 640–1,600 帧。
- **工具**：OpenCV SGBM 做深度伪标签；GTSAM 做因子图；标注格式统一为 `{episode, frame, T_B^K, mask, predicate}`。

### 6.3 合成人类干扰

- **官方备注驱动**：按 §1.6 的 `{object, action, direction, timing}` 在回放/2.5D 编辑里移动/移除/遮挡目标；生成“破坏→恢复”对。
- **实验室采集**：若自有/合作 G1，采 2–3 小时“人伸手移动物体/拿走/遮挡”的真实数据；这是 HIP 分类器的主数据。
- **增强**：手部遮挡、运动模糊、不同速度、不同方向；不要做全物理孪生。
- **负样本**：机器人自身运动、阴影、背景变化、干扰物；训练 HIP 不要把这些误判成人。

### 6.4 官方备注先验化

- 32×2 条备注 → JSON：`{task, object, action, direction, trigger_step, timing, prior}`。
- 对象名映射到任务物体本体（杯子/碗/插头/网线/锁/瓶子/盖子/拉链/笔盒/袋子/托盘/水果/积木/试管/工具/电池/耳机/手机/相框/书/盘子/杯子/球拍/字母/零食/药瓶/注射器）。
- 时机映射：“抓之前/之后”“叠了第二个之后”“快到了”“中途”“拉上之后”“合上之后”。
- 先验强度：命中 0.6–0.8，未命中均匀；可通过实验室数据校准。
- 推理时：语言指令/任务 ID 选先验；现场轨迹更新；不跨 episode 记忆。

### 6.5 数据配比/课程

```text
70% 官方 nominal 演示
20% 合成/实验室人类干扰 + 恢复
10% 困难负样本（遮挡、移走、未见物体、透明/反光）
```

- 任务均衡采样；过采样插入/悬挂/叠碗/拉链/开锁/装袋等高难任务。
- 课程：先 nominal，后干扰；先粗放置，后插入/闭合；先单臂，后双臂。
- 不要每任务 LoRA；一个模型 + 任务条件 token。

### 6.6 外部数据合规

- 手册未明文允许/禁止；默认只用官方 33k。
- 外部数据/仿真数据放开关后；邮件 `challenge_support@unitree.com` 确认。
- 若允许：优先补“人类干扰/恢复”“透明/反光/薄物体”“跨工位相机差异”，不要补同分布成功演示。
- 模型卡披露所有数据/预训练权重/感知组件。

## 7. 训练配方

### 7.1 模型

- **主干**：WLA-1.0-Base/GPR-VLA（6B 级）；LoRA + action expert；INT8/FP8 量化备选。
- **辅助头**：任务帧位姿回归、步骤谓词、变化检测、意图分类、放置目标；轻量（<50M）。
- **感知**：SGBM/平面拟合/因子图是确定性代码；分割/6D 头若学习，作为同一 checkpoint 的辅助头；现成网络只做离线教师。
- **单模型合规**：一个 checkpoint + 确定性几何；不按任务切换策略；模型卡列组件。

### 7.2 输入/输出

- **图像**：头双目 480×640（SML 用全分辨率；VLA 可 224×224/320×240）；双腕 480×640 或 320×320（VS 用全分辨率）。
- **状态**：双臂关节、EE base 位姿、夹爪、`lower_body`（含 waist）、上一动作。
- **语言**：整段指令；映射到任务/步骤图。
- **度量 token**：`T_B^T`、`T_T^K`、`T_B^EE`、`T_EE^W`、`Σ_K`、物体 ID/类型/尺寸。
- **意图 token**：人手/物体位置/速度、`P(g)`、`risk`。
- **输出**：动作 chunk（EE 优先；joint 备选）、夹爪、pivot 默认；辅助头。

### 7.3 损失

```text
L = L_action + λ_g L_gripper + λ_p L_pivot
  + λ_K L_taskframe + λ_pred L_predicate
  + λ_chg L_change + λ_int L_intent + λ_place L_placement
  + λ_con L_consistency
```

- `L_action`：flow matching / L1（按底座选）。
- `L_pivot`：小权重；只约束默认值/小幅变化，防漂移。
- `L_taskframe`：只在有标注/几何伪标签的帧。
- `L_consistency`：VLA 预测的任务帧与 SML 几何估计一致；变化 flag 与 SSG 回退一致。
- 不要用步骤分加权主损失；步骤分只做诊断/重试预算。

### 7.4 训练阶段

1. **感知预训练/标定**：SGBM + 平面/圆柱拟合 + 分割/6D 头（离线教师）；在 33k 上生成任务帧伪标签。
2. **适配器训练**：冻结 VLA，训练度量/意图/谓词头 + OPT 查表。
3. **联合微调**：LoRA + action expert + 辅助头；混入人类干扰/恢复数据。
4. **蒸馏/量化**：把教师感知蒸馏进辅助头；合并 LoRA；INT8/FP8；延迟压测。
5. **真机校准**：单任务调试验证 pivot/接口/安全；计分跑做发布门。

### 7.5 算力/量化

- **训练**：8×H100 80GB，1–2 周（LoRA/适配器为主）。
- **推理**：1×48GB 或 2×24GB（VLA + 感知/伺服分开）；FP16/FP8/INT8；KV cache/激活优化。
- **延迟**：VLA 3–5 Hz + chunk 8–16；感知 10 Hz；伺服 30 Hz；p99 <100 ms。
- **带宽**：4×480×640×3×10Hz ≈ 36 MB/s；如延迟高，头双目保 480×640、腕部降 320×320，或降帧率。

### 7.6 失败模式课程

- 抓空/滑落 → 重抓/柔顺。
- 放置偏移 → 任务帧重定位/腕部伺服。
- 插入失败 → 螺旋搜索/退避/重对中。
- 人被移动目标 → HIP 等待/重定位。
- 人被撤销步骤 → SSG 回滚/NRB 恢复。
- 遮挡/反光 → 换腕部视角/2D 回退。
- 超时 → 预算守卫/放弃非关键步骤（但成功率优先，别乱放弃终局）。

## 8. 实验矩阵

### 8.1 离线

| 实验 | 数据 | 指标 | 目的 |
|---|---|---|---|
| E0 基线 | 33k held-out | 动作误差、终端谓词通过率 | 基线 |
| E1 SML 深度/任务帧 | 640 episodes + 实验室标定物 | 深度误差、任务帧平移/旋转误差、跨任务泛化 | 证明厘米级任务帧 |
| E2 OPT | 32 任务 | 容器系释放位姿误差、σ 校准 | 证明少样本迁移 |
| E3 VS | 插孔/叠碗/挂杯回放 | 终端成功率、伺服步数、耗时 | 证明最后一厘米 |
| E4 HIP | 合成/实验室干扰 | 检测延迟、意图准确率、假阳性、恢复成功 | 证明意图先验 |
| E5 BRF | 双臂任务 | 相对位姿误差、碰撞率、终端成功 | 证明双手相对帧 |
| E6 延迟 | 4 图 + VLA + 感知 | p50/p99、动作平滑度 | 证明可部署 |

### 8.2 回放

- 用 held-out episode + 2.5D 编辑注入 human 干扰；测 HIP 检测/恢复、SSG 回退、MCF 重定位。
- 用不同容器位姿/背景/干扰物做 SML/OPT 的 cross-scene 回放。
- 回放不是真机；只做相对比较，不做绝对成功率承诺。

### 8.3 真机

- **每天 1 槽**；单任务调试只做接口/pivot/安全 smoke test（不计分）。
- **3–5 次计分跑**：R1 基线；R2 +SML/OPT/VS；R3 +HIP；R4 消融/最佳组合；R5 冲刺。
- 每次只改一个主变量；用 per-task 10 次明细诊断（哪一步失败、是否 human 试次、是否超时）。
- 由于排行榜取最好，别用“一次运气”下结论；看任务级一致性。

### 8.4 消融

- 双目 vs 单目；头双目 vs 头+腕；SML vs 2D 锚点；OPT vs 直接策略；VS on/off；HIP on/off；BRF on/off；MCF on/off；主动 base/arm 视角 on/off。
- 大部分离线/回放；真机只做 2–3 个关键消融。

### 8.5 指标/统计

- 主：per-task success rate、overall success、human-interference success、terminal-step success。
- 次：step score（诊断）、重定位延迟、任务帧误差、HIP F1/假阳性、恢复成功、p99、动作平滑度。
- 统计：按任务 bootstrap；报告 95% CI；不要只看总分。

### 8.6 证伪条件

- SML 任务帧误差 >2 cm（刚性物体）→ 砍 SML 主路径，回 2D+腕部。
- VS 在实验室插孔/叠碗提升 <5pp → 砍 VS 主路径。
- HIP 假阳性 >20% / 恢复 <40% → 只等待/只重定位。
- p99 >150 ms → 降感知/砍立体/换小模型。
- 真机 2 次计分跑无 +3pp → 回退到第 7 轮 PILOT + 小改进。

### 9.2 主投注详述

**I1 SML（为什么是“定位”而不是“深度”）**

- 深度只是中间量；任务要的是**容器/端口/杯架在 base 系里的 6D 位姿 + 协方差**。
- 三个帧：表帧（重力/高度）、任务帧（容器/目标）、工具帧（EE/腕）。
- 相对化：`T_B^EE* = T_B^K·H̄`；头部外参误差在相对量里抵消。
- 不确定度：`Σ_G=Σ_K+Σ_H`；决定直接执行/慢速/回退。
- 与 StereoVLA/ExStereo 的差异：不做端到端立体 token，而是**几何任务帧 + 腕部伺服**；与 Active Stereo ACT 的差异：用 G1 现成头双目 + 双腕，不额外加主动双目。
- 证据：StereoVLA +33.4% [P1]；ExStereo [P2]；FoveaVLA [P3]；Fast-FoundationStereo [P4]；Active Stereo ACT [P5]；CFVS [P16]。

**I2 HIP（为什么是“画像”而不是“避障”）**

- 避障只回答“别撞”；画像回答“他要干什么、我该等/退/回滚/重定位”。
- 官方备注是**任务条件先验**；现场轨迹是似然；贝叶斯更新。
- 输出不是“人是谁”，而是“意图/风险/受影响对象/建议动作”。
- 与 HINT/EgoRecovery/VLBiMan 的差异：把官方备注当先验、把 SSG 回退/NRB 恢复接起来；不采集身份。
- 证据：HINT [P8]；EgoRecovery [P9]；VLBiMan [P10]。

**I3 OPT+VS（为什么是“相对位姿 + 伺服”而不是“轨迹复制”）**

- 复制轨迹对位置/背景/外观不稳；相对释放位姿 H_i 是几何量，跨场景稳。
- 腕部相机在 0.1m 有 0.23mm/px；比头双目/2D token 高一个量级。
- settle-verify 把“放下去”变成“放稳且谓词保持”。
- 与第 7 轮 SVL 的差异：SVL 是 2D 锚点 + 缓放；VS 是 6D 任务帧 + 腕部误差 + 协方差门控。

**执行清单（主投注，按周可落地）**

- **SML**：① 用 `camera_params` 做 rectify/SGBM，验证 0.5/0.8/1.2 m 的深度误差；② RANSAC 桌面平面 + 圆柱/矩形拟合，输出 `T_B^K`；③ 用 waist/URDF/标定先验把点云变到 base；④ 因子图融合头双目 + 双腕 + proprio；⑤ 在 640 条 held-out episode 上评估任务帧误差；⑥ 集成进 `obs_delta_indices`（声明 `cam_right_high`）与 VLA token。
- **HIP**：① 把 32×2 条备注解析成 JSON；② 头双目背景建模 + 运动分割 + 手/物跟踪；③ 规则/逻辑回归先做意图后验；④ 实验室采 2–3 小时人类干扰数据训练/校准；⑤ 接 SSG 回退 + MCF 重定位 + NRB 恢复；⑥ 回放评估假阳性/恢复率；⑦ 真机门控（等待预算/限速）。
- **OPT+VS**：① 从 33k 提取每任务每步骤释放位姿 `H_i`；② 容器系稳健统计 + `τ_task`；③ 腕部手眼标定 + 像素级伺服；④ settle-verify + nudge/regrasp/retry；⑤ 在插孔/叠碗/挂杯回放上评估；⑥ 集成到 EE 控制空间；⑦ 真机只做 2–3 个关键消融。

### 9.3 修剪清单（明确不做）

- 全 32 任务高保真孪生/全物理（成本高、域差大）。
- 自由仿真数据/仿真 RL 主路径（合规/域差/时间）。
- 运行时仿真/MPC（延迟/复杂度）。
- 布料/拉链/透明全物理（用 2D/柔顺/回退，不硬做）。

- 每任务 LoRA/每任务策略（违反通才单模型精神，过拟合）。

- 外部数据默认开启（合规未知）。
- 把步骤分当主目标（口径错误）。

## 13. 开放问题（需邮件/调试槽确认）

1. **外部数据/预训练权重**是否允许？仿真数据？合作实验室数据？——手册未明文；默认关闭。
2. **`pivot[3:6]` 语义**：是腰/躯干/高度？单位/方向/安全范围？能否 base 小幅移动/升降？
3. **头部外参**：API 不给 `state_d435`/`state_torso`；能否用 waist FK + URDF？URDF 版本/安装误差？
4. **API 图像是否已整流**？头双目是否同步？`cam_right_high` 是否在所有机器人上可用？
5. **`get_action` 调用频率/控制频率**：chunk 消耗后多久再调用？是否有固定 30Hz？
6. **任务 ID/语言**：API 是否给任务 ID？只给语言字符串时，用 160 复述匹配是否可靠？
7. **10 次泛化**：同一任务 10 次是否同一机器人？跨任务随机？human 备注是否精确执行？
8. **单模型边界**：SGBM/几何/小型分割头是否算“多个模型”？现成感知网络是否允许？
9. **截止日期/榜单发布**：手册未给时间线；真实榜单何时上线？
10. **动作安全**：pivot 全零会怎样？超时/碰撞/人进入工作空间的终止规则？
11. **力/触觉**：API 是否只有夹爪开度？没有力控时，插入靠视觉/柔顺是否足够？
12. **腕部 IR**：API 只给 color；能否用 IR 双目？不能的话，腕部单目 + 已知几何。
