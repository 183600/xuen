# 第 13 轮（新循环第 1 轮）· GRASP-EXEC：先抓对，再插准——把 33k 成功演示变成「抓取先验 + 本体滑移监测 + 抓取系视觉伺服」

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1-1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新灵感循环第 1 轮，三个词是「视觉伺服」「抓取规划」「四足机器人」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是补上它们共同缺的前半段：**第一抓**，以及抓取之后的本体感知。

## 0. 先给结论：三条更正，一个押注

### 0.1 必须先更正的三条事实

1. **公开榜单目前是空的，不能把“榜首不到 30%”当事实。** 2026-10-31 抓取 [leaderboard.html](https://unibot.unitree.com/leaderboard.html)，页面只有“Coming Soon / 即将发布”，没有任何模型行；`leaderboard_data.json` 被 Tencent EdgeOne 拦截，返回 HTTP 567 的 HTML 而不是 JSON。第 12 轮写下的 MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9% 等 8 行分数，本轮无法复现，**应视为不可用，不再作为难度表、SOTA 或失败分布的依据**。这不是小修正：它意味着“围绕榜首差距设计创新点”这条路暂时不成立，先要有自己的测量。
2. **`action_chunk_size` 不是固定 30。** 官方 [README](https://github.com/unitreerobotics/unibot_submission) 明确它是 `int ≥ 1`，由选手在 `metadata` 里声明；[example_policy.py](https://github.com/unitreerobotics/unibot_submission/blob/main/example/example_policy.py) 用的是 8。30 只是 UnifoLM-WLA-1.0 的默认训练/推理 horizon，不是挑战赛强制。更准确地说：它在 handshake 时声明、每次 `get_action` 必须返回 `(T_a, ...)`，**整个提交内固定**；不能在某个阶段临时改成 3、另一个阶段改成 30。第 12 轮“30 步固定、可以按阶段改 chunk”的说法要改成“T_a 是提交级控制参数；VLA 规划 horizon 可以仍是 30，API 每次只返回 T_a 步”。
3. **腕部相机有内参。** [HangCup 的 meta/info.json](https://huggingface.co/datasets/unitreerobotics/G1_Dex1_HangCup/raw/main/meta/info.json) 里 `camera_params.wrist_left.color` / `wrist_right.color` 含 `camera_matrix`、`dist_coeffs`、640×480 和 `inverse_brown_conrady`；HangCup 的 `fx≈436.41, fy≈435.92, cx≈323.92, cy≈242.93`。缺的只是 wrist→EE 手眼外参。第 12 轮“腕部没有内参、只能先标定或仅做 2D 粗对齐”的判断过悲观；现在可以认真做米制 IBVS。

### 0.2 本轮的押注

> **VLA 是规划器，不是控制器。缺的那一层是“抓取执行器”：用 33k 成功演示检索第一抓的位姿与腕部目标图，用夹爪闭合签名 + EE 跟踪残差做本体感知的抓取成功/滑移检测，用腕部内参与抓取系视觉伺服补最后 3 厘米；VLA 仍然只做语义/相位规划。所有新增层都是确定性控制器，不引入第二个学习模型。**

一句话：**先抓对，再插准；先有可信私有基线，再谈榜单。**

### 1.2 API：哪些是硬约束

官方 [README](https://github.com/unitreerobotics/unibot_submission) 与 [example_policy.py](https://github.com/unitreerobotics/unibot_submission/blob/main/example/example_policy.py)（检索 2026-10-31）给出：

| 项 | 事实 | 对方案的影响 |
|---|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`，原生 480×640 RGB | 四路都可选；腕部可做近距伺服，头部双目可做 PBVS/深度 |
| 深度/力/触觉 | **没有** depth、camera_info、force/torque、tactile | 抓取成功检测必须靠视觉 + 夹爪/EE 本体信号 |
| `obs_delta_indices` | 键决定发哪些观测；值是 `≤0` 且严格递增的帧偏移，如 `[-10,-5,-2,0]`；`language` 必须 `[0]` | 可做时间堆叠；抓取闭合/滑移检测可用短历史窗口 |
| `action_chunk_size` | `int ≥ 1`，handshake 声明，每次返回 `(T_a, ...)`，提交内固定 | T_a 是控制参数，不是“固定 30”；扫 `{1,3,5,8,15,30}` |
| `control_space` | `"joint"` 或 `"ee"`，互斥 | 用 `"ee"` 才能直接接 WLA 的相对 EE + 绝对位姿适配 |
| ee 动作 | `action.left/right_ee_pose_gripper_base` `[6]`，base 系绝对 `xyz+rpy` | 视觉伺服输出绝对目标；WLA 输出相对位姿，必须 compose |
| `action.pivot` | `[7]`，shared，必须返回；README 只写“Lower-body / pivot target”，7 维布局/语义未定义 | 先给中性/观测值，单任务通道验证；不要盲目用它做全身控制 |
| `meta.token` | 每次 `get_action` 都要带，handshake 也校验 | 适配器必须透传 |
| 端口 | 从 8765 起 N 个连续端口；每端口独立 episode，`reset()` 隔离 | 每端口独立状态/历史/缓存；共享 GPU 推理要并发 |
| 延迟 | evaluator 记录每步延迟、抖动、动作统计 | p99 延迟是可信度指标；伺服不能拖慢主循环 |

README 没有明示线上控制频率；数据集是 30 fps。**先把 30 Hz 当工作假设，用单任务通道测实际周期**，不要写死。

### 1.5 数据实证：夹爪闭合签名真的存在

用 HF datasets-server 的 rows API 抽取 **6 个代表任务**（HangCup、PlugInEthernet、ZipUp、FoldTowel、StackBowls、Unlock）首个 episode 的前 300 帧（检索 2026-10-31；只是示例，不是全量统计）：

| 任务 | 首个 episode 观察（帧号） | 说明 |
|---|---|---|
| HangCup | 右夹爪 4.49 → 0.06（f69–80），右 EE z 0.09 → 0.28（f80–190），右夹爪 0.15 → 2.50（f167–175）；左夹爪恒 4.51 | 右臂抓取-抬升-释放的干净签名 |
| PlugInEthernet | 右夹爪 4.45 → 0.09，再回 4.57 | 抓取线缆后释放 |
| ZipUp | 左夹爪 4.49 → 0.05，右夹爪 4.50 → 0.37 | 双臂都参与 |
| FoldTowel | 左夹爪 2.01 → 0.00，右夹爪 3.11 → 0.02 | 双臂抓布 |
| StackBowls | 左夹爪 4.48 → 0.23，右夹爪 4.43 → 0.29 | 双臂叠碗 |
| Unlock | 左夹爪 4.48 → 1.27，右夹爪恒 4.46 | 左臂抓钥匙/锁 |

关键结论：

1. **夹爪开合不是二值，闭合后的停滞宽度携带物体宽度信息**，可作为“抓到了/没抓到”的本体信号。
2. **单臂和双臂任务都有**；抓取先验必须按 arm 分别建库。
3. 夹爪数值约 0–4.6，满行程 90 mm；单位/归一化 README 未明示，**必须用数据分布 + 单任务通道校准**，不能假设 0–1。
4. **`action.gripper_controls` 不能直接当开合目标**：HangCup 中 `ctr[2]` 在 f85 已回到 10（开），但 `action.right_gripper` 到 f168 仍为 0.0235；主命令用 `action.left/right_gripper`，`gripper_controls` 只作辅助。

### 1.6 WLA：6B / 30 步 / 相对 EE / 24GB 可微调

[UnifoLM-WLA-1.0 README](https://github.com/unitreerobotics/unifolm-wla)（检索 2026-10-31）：

- 6B 参数，约 2,500 小时真机数据，64 个任务（桌面 + 全身），支持二指夹爪和五指手。

- 统一状态 **60 维**；EE 状态是绝对位姿 + rotation-6D。
- 微调文档 [`train_action_expert_en.md`](https://github.com/unitreerobotics/unifolm-wla/blob/main/docs/train_action_expert_en.md)：冻结 VLM，只训 DiT action head + robot-state projector，默认单张 24GB GPU。
- **动作是相对当前 EE 的**；挑战赛 API 要绝对位姿。适配器必须 `T_BE^cmd = T_BE^obs · exp(Δξ)`，再转 rpy；不能直接把 WLA 的 54 维塞进 API。

### 1.7 规则：单模型、32×10、5 类泛化

飞书参赛手册（[中文](https://scnhkkqlu12w.feishu.cn/docx/Uz7OdFBcDoqP1dxgH62cHW1CnMh)、[英文](https://scnhkkqlu12w.feishu.cn/docx/ZNHIdaGx0oPOlBxNVxkcswqqnnh)，检索 2026-10-31）：

- 所有任务必须基于**同一模型**；模型类型不限（World Model、VLA 均可）。
- 32 个任务，每任务 10 次；5 类泛化各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
- 单次真机上限 **180 s**；排名先看 32 任务总平均成功率，再看总平均步骤分，再相同看更早提交。
- 跨 **N 台机器人**；从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 必须隔离。
- 有**不计分的单任务测试通道**，可用于单任务 A/B。

**对方案的约束**：抓取先验/本体监测/视觉伺服都必须是确定性控制器或无学习权重的查表/几何计算；唯一的可学习策略仍是 VLA。

## 2. 诊断：为什么是“第一抓 + 最后 3 厘米”

把一次桌面操作拆成两段：

```text
A 段：接近 → 对齐 → 闭合 → 抬升
       失败模式：没对准、夹到空气、夹到边缘、宽度不够、撞到邻近物、抓取后滑落
B 段：搬运 → 插入/挂/叠/拉链/拧 → 释放
       失败模式：最后 1–3 cm 偏了、接触力不对、物体被人移动、chunk 内看不到
```

第 10 轮 FACT-VLA 解决“相位化 BC + 柔顺执行”；第 11 轮 GEO-RESIDUAL 解决“动作解释不了的三维残差/编辑检测”；第 12 轮 CHUNK-SERVO 解决“B 段的 30 步开环 chunk”。它们共同的前提是：**A 段已经抓到了**。但 33k 演示里，A 段恰恰是最值得白嫖的监督：

- 每条成功演示都至少有一次成功抓取；`state.left/right_ee_pose_gripper_base` 给出抓取时的 EE 位姿；`state.left/right_gripper` 给出闭合宽度；腕部视频给出抓取前的目标图。
- 失败的重试/滑移没被标注，但**闭合停滞宽度**和**抬升后的 EE 轨迹**可以把“抓到了”与“没抓到”分开。
- 这些信号不需要新模型，只需要离线挖库 + 在线查表 + 几何打分。

四足机器人的启发不是“把 G1 当四足”，而是：

1. **本体感知可以在没有力/触觉传感器时估计接触**（CoRL 2021、CoPRE）；
2. **滑移可以被检测并触发反射恢复**（Focchi 2018、Sensors 2022）；
3. **视觉退化时靠本体 + 历史完成动作**（盲走/状态估计）；
4. **浮动基座的平衡/补偿**可以让末端在执行中更稳（G1 的腰/腿/`pivot`）。

对应到桌面操作：**夹爪闭合签名 = 足端接触；物体相对夹爪滑动 = 足端滑移；抓取失败重试 = 反射恢复；腕部遮挡时的本体 dead-reckoning = 盲走。**

## 3. 方法：GRASP-EXEC

### 3.1 总架构

```text
                 ┌──────────────────────────────────────────┐
                 │ Evaluator (N ports 8765..8765+N-1)        │
                 └───────────────┬──────────────────────────┘
                                 │ obs / action chunk (T_a)
                                 ▼
                 ┌──────────────────────────────────────────┐
                 │ Per-port GRASP-EXEC (CPU, deterministic)  │
                 │  ├─ phase detector (approach/grasp/...)   │
                 │  ├─ GRASP-PRIOR: demo retrieval + scoring │
                 │  ├─ PROPRIO-GRASP: closure/slip monitor   │
                 │  ├─ GRASP-SERVO: IBVS/PBVS in grasp frame │
                 │  ├─ CHUNK-SCHED: T_a slice + plan cache   │
                 │  └─ adapter: WLA 54D → API absolute EE    │
                 └───────────────┬──────────────────────────┘
                                 │ async, batched
                                 ▼
                 ┌──────────────────────────────────────────┐
                 │ Shared VLA server (GPU)                   │
                 │ UnifoLM-WLA-1.0 / VLA-0, plan horizon 30  │
                 └──────────────────────────────────────────┘
```

- **唯一学习模型**：VLA（官方 WLA 微调 action head，或直接用 Base）。
- **确定性层**：抓取先验检索、几何打分、闭合签名、滑移检测、IBVS/PBVS、chunk 切片。
- **数据资产**：33k 成功演示 → 抓取关键帧库 + 夹爪闭合统计 + 腕部目标图；不是第二个模型。
- **仿真**：只做标定/风洞，不训策略。

### 3.2 GRASP-PRIOR：从成功演示里挖“第一抓”

**离线挖库**（每条 episode 一次）：

1. **相位切分**：用 `action.left/right_gripper` 目标与 `observation.state.*_gripper` 观测、EE 速度切 `approach → close → lift → transport → place/insert → release`；`gripper_controls` 只作辅助。
2. **抓取事件**：
   - `t_close`：夹爪命令开始闭合，或 `|ġ|` 超过阈值；
   - `t_stall`：闭合过程中 `|ġ| < ε` 连续 K 帧，且命令处于闭合侧（允许已饱和到全闭）；
   - `t_lift`：`t_stall` 之后 EE z 上升 > 2 cm；
   - `t_release`：命令打开且 `g` 上升。
3. **关键帧**：`t_pre = t_close - Δ`（Δ≈10–15 帧，取闭合前、EE 稳定的一帧）、`t_stall`、`t_lift`。存：
   - `T_BE(t_pre)`、`T_BE(t_stall)`、`T_BE(t_lift)`（base 系）；
   - `g(t_pre)`、`g* = median(g(t_stall-K:t_stall))`；
   - 抓取腕部图 `I_wrist(t_pre)` 与头部图 `I_head(t_pre)`；
   - 语言/task、arm、approach 方向、闭合时长；
   - 抓取处宽度 `w_grasp`（由 `g*` 反推）；物体整体宽度 `w_obj`（由头部双目 ROI 估计，可选）。
4. **归一化**：把抓取位姿表示成相对物体局部系的 `T_EO*`（若物体位姿可估），否则存相对桌面/物体质心的 `T_BE*` + `w_grasp`。运行时用当前物体位姿把 `T_EO*` 变回 `T_BE^d = T_BO · (T_EO*)⁻¹`。

**在线检索**（每个抓取相位一次）：

- Query：task/language、arm、当前腕部 ROI 描述子、当前抓取处宽度、接近方向。
- 候选打分：

```text
S = λ1·Q_visual + λ2·Q_width + λ3·Q_antipodal
  + λ4·Q_reach  + λ5·Q_collision + λ6·Q_prior
```

  - `Q_width = exp(-((w_grasp + 2δ - g*)/σ_w)^2)`，硬约束 `w_grasp + 2δ ≤ 90 mm`（`w_grasp` 是抓取处局部宽度，不是物体整体宽度）；
  - `Q_antipodal`：爪轴与物体短轴/接触法线对齐；用 ROI 的 PCA 或双目点云法线；
  - `Q_reach`：IK 残差 + 关节限位余量；
  - `Q_collision`：预抓取/抓取位姿到桌面、邻近物体、机器人自身的最小距离；
  - `Q_visual`：腕部目标图与当前图的局部特征相似度（ORB/颜色直方图，或同一 VLA checkpoint 的 encoder 特征，C3 合规）；
  - `Q_prior`：该 task/arm/相位在演示库中的出现频率。
- 取 top-k，按 `Q_reach × Q_collision` 过滤，选最高分；置信度低时回退 VLA 原始动作。

**执行**：

1. 预抓取：先到 `T_BE(t_pre)` 的物体相对版本；爪轴对准短轴；
2. 精细对齐：腕部 IBVS 对齐到 `I_wrist(t_pre)` 的抓取点/爪轴；
3. 闭合：按演示的闭合速度/时长；进入 PROPRIO-GRASP 验证；
4. 抬升：慢速抬升 1–2 cm，检测滑移；失败则换下一个候选。

### 3.3 PROPRIO-GRASP：把夹爪当“力/触觉传感器”

**闭合签名**（每个 arm 独立）：

- 记命令 `u_g(t)`（闭合方向）与观测 `g(t)`。
- 闭合中若 `|g(t)-g(t-1)| < ε` 连续 K 帧，且 `u_g` 处于闭合侧（允许已饱和到全闭）→ **停滞**。
- 停滞宽度 `g*`；空闭合宽度 `g_empty` 用演示中“没夹到物体”的样本或全库最小 `g`（所有帧，不是 `g*`）校准；用 `g*` 会高估 `g_empty`。
- 判定：`g* - g_empty > δ_g` → 抓到；否则 → 空抓。
- 也可用命令停滞点：`u_g*` 离全闭还有距离 → 有物体；但**命令饱和时不能作为否决条件**（HangCup 目标 `action.right_gripper` 在 f80 已到全闭 0.0235，`g*≈0.154` 在 f83–84 稳定；主判据仍是 `g* - g_empty`）。

**滑移检测**：

- 视觉：腕部图中物体 ROI 与爪中心的相对位移；闭合且 EE 运动时，若相对位移 > δ_pix 连续 K 帧 → 滑移。
- 本体：闭合命令不变时 `g(t)` 突变（物体被挤/滑/变形）→ 滑移。
- 融合：`s_t = α·1[visual] + β·1[width change]`；`s_t > θ` 触发。
- 头部视角兜底：物体相对桌面移动而 EE 未动 → 滑移/被拿走。

**状态机**：

```text
IDLE → APPROACH → ALIGN → CLOSE → VERIFY → LIFT → TRANSPORT → PLACE → RELEASE
        失败：VERIFY miss → 开爪、后退、换候选、重试（≤3）
              LIFT/TRANSPORT slip → 停止、下降、重抓或请 VLA 重规划
              TIMEOUT → 安全回退
```

**四足映射**：足端接触 ↔ 夹爪接触；足端滑移 ↔ 物体滑移；步态相位 ↔ 操作相位；反射恢复 ↔ 重抓/重规划；本体状态估计 ↔ EE/夹爪/关节历史。

### 3.4 GRASP-SERVO：在抓取系里做视觉伺服

- **腕部 IBVS**：用已确认的内参 `K_w` 和畸变模型；特征 `s=(u,v)` 取物体抓取点/爪轴端点；目标 `s*` 来自演示腕部图。经典交互矩阵：

```text
L_s = [[-f/Z, 0, u/Z, uv/f, -(f²+u²)/f, v],
       [0, -f/Z, v/Z, (f²+v²)/f, -uv/f, -u]]
v_c = -λ L_s⁺ (s - s*)
```

  其中 `u,v` 是去畸变、相对主点的像素坐标（px），`f` 是像素焦距，`Z` 用米；`Z` 可用头双目/物体先验。
- **手眼标定**：wrist→EE 外参未知。两条路：
  1. 棋盘格/已知靶标 + OpenCV `calibrateHandEye`（AX=XB），重投影 ≤5 px；
  2. **用演示自标定**：成功抓取时腕部图看到物体、EE 位姿已知，优化 `T_CE` 使物体抓取点/爪轴投影一致；不需要额外标定板，但需要足够多的抓取样本。
- **在线交互矩阵**：若手眼外参有误差，用 Broyden 更新 `L_s`：每次已知 EE 小运动后，用观测到的图像特征变化修正 `L_s`；适合最后 1–2 cm。
- **PBVS**：头部双目估 `T_BO`，`T_BE^d = T_BO · (T_EO*)⁻¹`，`e = log(T_BE⁻¹ T_BE^d)`；适合 3–5 cm 接近/插入轴对齐。
- **混合**：远 PBVS、近 IBVS；腕部被夹爪/物体遮挡时回退 PBVS 或本体 dead-reckoning。
- **前馈 + 反馈**：`a_cmd = a_ff ∘ exp(Δa)`；每步限幅（如 1 cm / 0.05 rad）；接触段法向缩幅；延迟用 RTT 测量 + 常速预测补偿。
- **安全**：工作空间、速度、最大重试、异常即停；不依赖力传感器。

### 3.5 CHUNK-SCHED：T_a 是提交级参数

- 正确约束：`T_a` 在 handshake 声明、提交内固定；VLA 规划 horizon `H_plan` 可以仍是 30。
- 设计：每次 `get_action` 返回 `T_a` 步；VLA 后台每 `H_plan` 步产出一个 plan；伺服每个 chunk 用最新观测修正；若 plan 过期则重查。
- 扫 `T_a ∈ {1,3,5,8,15,30}`：小 T_a 反应快但推理/网络开销占比高；大 T_a 摊销推理但开环久。用单任务通道测 `p99` 延迟与成功率，选 knee。
- 参考 RTC/REMAC：异步推理 + chunk 内修正能减少停顿；但 REMAC 要训练、RTC 要改去噪，本轮先做“plan cache + servo”，把 RTC 作为后续升级。

### 3.6 Adapter：WLA 54D → API 绝对 EE

```text
T_BE^cmd = T_BE^obs · exp(Δξ_rel)      # Δξ_rel 来自 WLA [0:6]/[13:19]
rpy_cmd  = R2rpy(R_BE^cmd)
action.left_ee_pose_gripper_base  = [xyz_cmd, rpy_cmd]
action.left_gripper = map_gripper(wla_gripper)   # 单位/方向需校准
action.pivot = neutral_or_observed_pivot         # 7 维布局未定义，先保守
```

- WLA 的 `[6:7]`/`[19:20]` 夹爪命令是 raw scalar；挑战赛 `[1]` 也是 raw scalar，但量纲未明示。用数据分布 + 单任务通道校准映射。
- `action.pivot [7]` 必须返回；先用中性值/观测值，不要让它和手臂打架。
- 若 `control_space="joint"`，需要 IK；本轮优先 `"ee"`，与 WLA 相对 EE 更接近。

### 3.7 不做什么

- 不从零训 6B/14B VLA/World Model（官方 WLA 已做完，算力不划算）。
- 不引入第二个学习策略/残差网络/独立视觉编码器做在线决策（单模型合规风险）。
- 不做力/触觉闭环（API 没有）。
- 不做逐任务策略（规则禁止，且不泛化）。
- 不把空榜单当难度表；不把第 12 轮的 29.7% 当 SOTA。
- 不在 `pivot` 语义未验证前做全身控制。

## 6. 实验门 G0–G8

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | 腕部手眼能否标定？ | 重投影 ≤5 px；腕部 ROI 有效率 ≥70% | 用演示自标定；仍失败则只用头双目 PBVS |
| G1 | 抓取先验是否可信？ | top-5 含可行抓取 ≥80%；位姿误差 ≤5 mm/2° | 退化为任务级固定预抓取 |
| G2 | 闭合签名能否判抓取？ | 离线成功率/失败判定的 balanced accuracy ≥90%；误报 ≤5% | 只做保守重试，不自动判失败 |
| G3 | 滑移能否检出？ | 离线/扰动数据 recall ≥80%，检测延迟 ≤100 ms | 只做抬升后视觉确认 |
| G4 | 伺服是否收敛？ | 横向 ≤2 mm、深度 ≤3 mm、2 s 内 ≥95%（仿真/台架） | 降增益/只做 PBVS/加 T_a |
| G5 | T_a 扫出 knee？ | 最佳 T_a 比默认 8/30 在成功率或 p99 延迟上更优 | 固定保守 T_a=5 |
| G6 | 单任务 A/B 是否涨点？ | 3/5 任务 +10pp；FoldTowel 不回归 >5pp | 不提交 GRASP-EXEC 版本 |
| G7 | 人为干扰能否恢复？ | 检测 ≤200 ms；仿真恢复 ≥70% | 只做离线标注/不线上触发 |
| G8 | 32 任务干跑稳定？ | N 端口隔离、reset 干净、内存不涨、p99 ≤150 ms | 回退基线 |

所有门先在离线回放和单任务不计分通道上过；没有过门，不烧正式提交。

## 7. 风险与合规

**合规分级**：C1=离线查表资产；C2=确定性控制器；C3=同一 VLA checkpoint 的冻结 encoder。三者都不构成“第二个学习策略”。

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定为第二个模型 | 抓取先验是查表+几何打分；闭合/滑移是确定性信号处理；伺服是控制器；提交材料写清楚 C1/C2/C3 |
| 手眼标定误差/漂移 | IBVS 偏 | 棋盘格一次 + 演示自标定 + Broyden 在线修正；误差大回退 PBVS |
| 腕部遮挡/透明/反光 | 视觉失败 | 头部双目 PBVS、本体 dead-reckoning、闭合签名兜底 |
| 夹爪量纲未知 | 映射错 | 用数据分布 + 单任务通道校准；先保守限幅 |
| `pivot` 语义未知 | 全身动作异常 | 先中性值；单任务验证；不依赖 |
| 抓取先验 mismatch | 抓错 | 任务/arm/相位过滤；top-k 重打分；置信度低回退 VLA |
| 滑移误报 | 频繁重抓 | 滞回 + 多帧窗口 + 视觉/本体融合；限重试 |
| 远程延迟/抖动 | 伺服不稳 | T_a 扫描；RTT 测量；预测补偿；p99 监控 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |
| 数据泄漏 | 离线指标虚高 | 按 episode/session/物体/背景分组划分；相邻帧不跨 split |
| 安全 | 碰撞/夹手 | 限速/限幅/工作空间/最大重试；异常即停 |

# 第 13 轮产物 · GRASP-EXEC 技术报告

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1-1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「GRASP-EXEC」的工程化产物；它**取代**第 12 轮产物中关于榜单分数、固定 30 步 chunk、腕部无内参的三条错误事实，但保留第 10/11/12 轮的相位化 BC、动作条件化残差、执行层闭环架构。

## 0. 结论与边界

### 0.1 三条更正

1. **榜单是空的。** [leaderboard.html](https://unibot.unitree.com/leaderboard.html)（检索 2026-10-31）只有“即将发布 / Coming Soon”；`leaderboard_data.json` 返回 EdgeOne HTTP 567 HTML，不是 JSON。第 12 轮的 8 行分数表不可复现，本报告不再引用任何模型分数、任务难度排名或失败分布。

3. **腕部相机有内参。** [meta/info.json](https://huggingface.co/datasets/unitreerobotics/G1_Dex1_HangCup/raw/main/meta/info.json) 的 `camera_params.wrist_left.color` / `wrist_right.color` 含 `camera_matrix`、`dist_coeffs`、640×480、`inverse_brown_conrady`；HangCup `fx≈436.41, fy≈435.92, cx≈323.92, cy≈242.93`。缺的只有 wrist→EE 外参。

### 0.2 本报告交付什么

- **GRASP-PRIOR**：从 33k 成功演示挖抓取关键帧，建 task/arm/phase 条件库，在线检索 + 几何打分 + 执行。
- **PROPRIO-GRASP**：夹爪闭合签名、空闭合校准、抓取成功判定、跟踪残差、滑移检测、状态机、反射恢复。
- **GRASP-SERVO**：腕部内参 + 手眼标定/自标定 + IBVS/PBVS + 在线交互矩阵 + 延迟补偿。
- **CHUNK-SCHED**：T_a 扫描、plan cache、周期模型、RTC/REMAC 的边界。
- **Adapter**：WLA 54D 相对 EE → 挑战赛绝对 EE；夹爪/`pivot` 保守映射。
- **私有基线 + G0–G8**：在空榜单下先建立可信测量，再决定投什么。

### 0.3 不做什么

- 不从零训 VLA/World Model；不引入第二个学习策略/残差网络/独立视觉编码器做在线决策。
- 不做力/触觉闭环（API 没有）；不做逐任务策略；不在 `pivot` 语义未验证前做全身控制。
- 不把空榜单当难度表；不把第 12 轮的 29.7% 当 SOTA。

## 2. 问题形式化

### 2.1 坐标系与符号

| 符号 | 含义 |
|---|---|
| `B` | 机器人 base 系 |
| `E_L, E_R` | 左/右夹爪 EE 系（TCP） |
| `W_L, W_R` | 左/右腕相机光学系 |
| `H_L, H_R` | 头部左/右相机光学系 |
| `O` | 物体系（质心 + PCA 轴） |
| `G` | 抓取系（爪中心 + 爪轴 + 接近轴） |
| `T_XY` | 从 Y 到 X 的 4×4 变换 |
| `g` | 夹爪开合观测（数据约 0–4.6） |
| `u_g` | 夹爪闭合命令（0=开，1=闭，方向待校准） |
| `T_a` | API `action_chunk_size`（提交级常量） |
| `H_plan` | VLA 规划 horizon（默认 30） |

### 2.2 状态与动作

```text
s_t = (q_L, q_R, T_BE_L, T_BE_R, g_L, g_R,
       I_HL, I_HR, I_WL, I_WR, ℓ)

a_t = (T_BE_L^cmd, T_BE_R^cmd, u_L, u_R, p)
```

- `q` 是 7 维臂关节；`T_BE` 是 base 系 EE 位姿；`I` 是图像；`ℓ` 是语言；`p` 是 `pivot [7]`。
- 每端口独立维护 `s` 的历史、相位、plan cache、抓取候选、重试计数。

### 2.3 抓取规划问题

给定 `s_t` 和目标物体/受器，求预抓取 `T_BE^pre` 与抓取 `T_BE^g`，满足：

```text
1) w_grasp + 2δ_margin ≤ 90 mm
2) jaw_axis(T_BE^g) ≈ object_minor_axis(O)
3) approach_axis(T_BE^g) 与表面法线/可行方向夹角 ≤ θ_a
4) IK(T_BE^pre), IK(T_BE^g) 有解，关节限位余量 ≥ q_margin
5) 预抓取/抓取/抬升路径与桌面、邻近物、自身无碰撞
6) 腕部相机在 T_BE^pre 能看到抓取点
7) Q_grasp(T_BE^g) ≥ Q_min
```

`Q_grasp` 用可解释的加权分，不用第二个学习模型：

```text
Q_width     = exp(-((w_grasp + 2δ - g*)/σ_w)²)
Q_antipodal = exp(-((1 - |j · m|)/σ_a)²)
Q_reach     = exp(-(||IK_residual||/σ_q)²)
Q_collision = exp(-(d_min/σ_c)²)
Q_visual    = cos(φ(I_W(t)), φ(I_W*))
Q_prior     = count(task, arm, phase) / max_count
S           = Σ λ_i Q_i
```

- `j` 是爪轴，`m` 是物体短轴；`d_min` 是路径/位姿到障碍的最小距离；`φ` 是颜色直方图/ORB/同一 VLA encoder 特征。
- 硬约束（1–6）先过滤，再按 `S` 排序；top-k 里选 `Q_reach×Q_collision` 最高的。

### 2.4 抓取成功与滑移估计

```text
抓取成功 y_g ∈ {0,1}：
  y_g = 1  iff  g* - g_empty > δ_g
  # u_g* 未到全闭只作置信度加分；命令饱和时不能否决
滑移 y_s ∈ {0,1}：
  y_s = 1  iff  visual_slip > θ_v  或  |Δg| > θ_g（命令不变时）
```

- `g*` 是闭合停滞宽度；`g_empty` 是空闭合宽度；`u_g*` 是停滞时的命令。
- 视觉滑移：腕部图中物体 ROI 相对爪中心的位移；头部视角：物体相对桌面移动而 EE 未动。

### 2.5 视觉伺服问题

```text
IBVS:  s = (u,v) 或爪轴两端点；s* 来自演示腕部图/几何目标
       e = s - s*；v_c = -λ L_s⁺ e
PBVS:  e = log(T_BE⁻¹ T_BE^d)；v = -λ e
混合:  远 PBVS、近 IBVS；腕部遮挡回退 PBVS/本体 dead-reckoning
```

约束：每步限幅（如 1 cm / 0.05 rad）、接触段法向缩幅、RTT 预测、异常即停。

### 2.6 Chunk 调度问题

```text
t_cycle = T_a / f_ctrl + τ_infer + τ_net
f_eff   = T_a / t_cycle
```

- `T_a` 越小，反馈越频繁，但推理/网络开销占比越高；`T_a` 越大，越开环。
- 目标：在 `p99` 延迟可接受的前提下，选使成功率/步骤分最好的 `T_a`；不是“越大越稳”或“越小越快”。

## 3. 演示挖掘管线（GRASP-PRIOR）

### 3.1 数据读取与字段裁剪

- 用 HF `datasets-server` rows API 或 parquet 读取每个 episode 的：
  - `observation.state.left/right_arm`、`left/right_gripper`、`left/right_ee_pose_gripper_base`、`lower_body`、`waist_state_joint`；
  - `action.left/right_gripper`、`action.gripper_controls`、`action.left/right_ee_pose_gripper_base`；
  - `frame_index`、`episode_index`、`timestamp`、`task_index`；
  - 腕部/头部视频帧（按 `frame_index` 取）。
- 全量 33k episodes 不必一次性下载视频；先读状态/动作 parquet 定位抓取事件，再按事件取帧。这样存储从 TB 级降到几百 MB 级的关键帧库。

### 3.2 相位切分

对每个 arm 独立：

```text
1) 计算闭合命令 u_g(t)：
   - 数据里优先用 action.left/right_gripper（目标开合，raw 0–4.6）；gripper_controls 只作辅助（语义不确定）；
   - 线上用 action.left/right_gripper 的标量，经校准映射。
2) 计算 g(t)、Δg(t)、EE 速度 v(t)、EE z(t)。
3) 事件：
   t_close   = 第一个 u_g 持续上升（闭合）的帧
   t_pre     = t_close - Δ_pre（Δ_pre≈10–15 帧；必须是闭合前、EE 已稳定的帧）
   t_stall   = t_close 后 |Δg| < ε 连续 K 帧，且 u_g 处于闭合指令（允许已饱和到全闭）
   t_lift    = t_stall 后 z(t) - z(t_stall) > 0.02 m
   t_release = u_g 持续下降（打开）且 g 上升
4) 段：
   approach  = [t_pre, t_stall)
   grasp     = [t_stall, t_lift)
   transport = [t_lift, t_release)
   release   = [t_release, end)
```

建议初值：`K=3–5` 帧（100–167 ms），`ε` 用 `g` 的噪声标准差（离线估计），`Δ_pre=10–15` 帧（333–500 ms）。所有阈值用每任务/每 arm 的分位数校准，不写死。

### 3.3 抓取事件质量过滤

不是每个 `t_stall` 都是成功抓取。过滤：

- `t_lift` 存在，且抬升高度 > 2 cm；
- 抬升后 `g` 仍显著大于 `g_empty`；
- EE 轨迹在抬升段没有同时出现 `g` 的剧烈变化（滑移/掉落）；
- 物体在腕部/头部 ROI 中随 EE 移动（视觉一致性）；
- 若 `t_lift` 后 10 帧内 `g` 回到 `g_empty`，判为失败，剔除。

这样得到“成功抓取”库；失败样本单独存，用于校准 `g_empty` 和滑移阈值。

- **有头部双目**：用 rectified 双目 + ROI 分割（颜色/深度/经典几何；不要新增分割模型，除非是同一 VLA encoder）估 `T_BO` 和物体尺寸；`T_EO* = T_BE_grasp⁻¹ T_BO`。
- **没有可靠深度**：用腕部图 + 已知抓取处宽度 `w_grasp`，把抓取点表示成 `(u*, v*, θ_jaw, w_grasp)`；运行时用当前腕部图对齐。
- **透明/反光/变形物体**：降低几何置信度，改用腕部图模板 + 闭合签名；不要强行估 6D 位姿。

### 3.6 检索与打分

Query：

```text
q = (task/language, arm, phase, current_wrist_ROI, w_grasp, approach_hint)
```

候选打分（§2.3）：`S = Σ λ_i Q_i`。建议初值：

```text
λ_visual=0.30, λ_width=0.20, λ_antipodal=0.20,
λ_reach=0.15, λ_collision=0.10, λ_prior=0.05
```

- `Q_width` 是硬约束，先过滤 `w_grasp+2δ > 90 mm`。
- `Q_visual` 用局部 patch 的颜色直方图 + ORB 匹配；若用 VLA encoder，必须同一 checkpoint（C3），不能另训视觉模型。RAGrasp 的 DINOv2/SAM2 只作为离线检索思想参考，**不要作为第二个在线视觉编码器**；否则单模型合规存疑。
- 置信度：`c = max S`；`c < c_min` 时回退 VLA 原始动作，不强行抓。

```text
3) 精细对齐：腕部 IBVS 到腕部目标 patch 的抓取点/爪轴
```


## 4. 本体感知抓取/滑移监测（PROPRIO-GRASP）

### 4.1 闭合签名

对每个 arm：

```text
u_g(t) ∈ [0,1]   # 0=开，1=闭（方向用数据/单任务通道校准）
g(t)             # 观测开合，数据约 0–4.6
Δg(t) = g(t) - g(t-1)
```

闭合段（`u_g` 进入闭合指令，允许已饱和到全闭）中，若：

```text
|Δg(t)| < ε  for K consecutive frames
且 u_g(t) ≥ u_close        # 只要求仍在闭合侧，不要求仍在上升
```

则判停滞；`g* = median(g(t-K+1..t))`，`u_g* = median(u_g(t-K+1..t))`。

**HangCup 实例说明为什么不能要求“命令仍在上升”**：右夹爪目标 `action.right_gripper` 在 f80 已到全闭 0.0235 并保持，观测 `g` 在 f83–84 才稳定在 0.154；若要求命令继续上升，会漏掉这次成功抓取。命令饱和时，成功判据必须依赖 `g*`，不能依赖命令未饱和。

### 4.2 空闭合校准

`g_empty` 的三种来源，按优先级：

1. **演示中的失败/空抓样本**：`t_lift` 后 `g` 回到最小值的样本；
2. **全库最小 `g`（所有帧，不是 `g*`）**：取 1–5 分位；`g*` 总是物体宽度，用 `g*` 会高估 `g_empty`；
3. **单任务通道主动校准**：在空工作空间闭合一次，记录 `g`。

`δ_g` 用 `g` 的噪声/量化步长 + 物体最小宽度先验；建议 `δ_g = max(3σ_g, 0.5 mm 当量)`，再用单任务通道调。

### 4.3 抓取成功判定

```text
y_g = 1  iff  (g* - g_empty > δ_g)
c_g = sigmoid((g* - g_empty - δ_g) / σ_g)
# u_g* < 1 - δ_u 只作为加分项/置信度修正，不是必要条件：
# 命令可能已饱和到全闭，而 g* 仍因物体厚度停在 g_empty 之上。
```

- 若 `g*` 接近 `g_empty` → 空抓（无论命令是否饱和）。
- 若 `g*` 很大且 `u_g*` 未饱和 → 有物体。
- 若 `g*` 很大但 `u_g*` 已饱和 → 可能夹到薄壁/边缘，需视觉确认。
- 用 `c_g` 决定重试/继续；不要只用二值。

### 4.4 跟踪残差

```text
r_pos(t) = ||p_BE^cmd(t) - p_BE^obs(t)||
r_rot(t) = angle(R_BE^cmd(t)ᵀ R_BE^obs(t))
r(t)     = [r_pos, r_rot]
```

- 自由空间：`r` 小；接触/受阻：`r` 在约束方向增大。
- 用 `r` 做接触代理：`contact_score = sigmoid((r - r0)/σ_r)`；`r0` 用自由空间分位数校准。
- 注意：`r` 也包含控制器跟踪误差/延迟；必须用同机器人、同速度的自由空间数据校准，不能跨机器人写死。
- 用途：调制伺服增益（接触时降增益/法向缩幅）、检测“推不动”（可能撞到/插入偏了）、触发重试。

### 4.5 滑移检测

**视觉滑移**：

```text
在腕部图跟踪物体 ROI 的质心 c_obj(t) 与爪中心 c_jaw(t)
d(t) = ||c_obj(t) - c_jaw(t)||
若闭合且 EE 运动，d(t) - d(t-1) > δ_pix 连续 K 帧 → 视觉滑移
```

**本体滑移**：

```text
若 u_g 不变，|g(t) - g(t-1)| > δ_g 连续 K 帧 → 宽度突变（滑移/变形/挤压）
```

**融合**：

```text
s_t = α·1[visual_slip] + β·1[width_change]
y_s = 1 iff s_t > θ_s
```

建议 `α=0.6, β=0.4`，`θ_s=0.5`；用离线扰动数据调。头部视角兜底：物体相对桌面移动而 EE 未动 → 滑移/被拿走。

### 4.6 状态机

```text
IDLE
  → APPROACH      (VLA/先验给出预抓取)
  → ALIGN         (PBVS/IBVS，误差 < e_align)
  → CLOSE         (u_g 进入闭合侧，允许饱和；等待停滞)
  → VERIFY        (y_g/c_g)
      失败 → OPEN → BACKOFF → next candidate (≤3)
      成功 → LIFT
  → LIFT          (慢速 z+；滑移检测)
      滑移 → STOP → LOWER → RE-GRASP/REPLAN
  → TRANSPORT     (VLA 规划 + 伺服)
  → PLACE/INSERT  (接触段降增益/法向缩幅)
  → RELEASE       (u_g 下降；确认 g 上升)
  → DONE
超时/异常 → SAFE_HOLD
```

每个状态有超时（按演示相位时长分位数 + 余量），超时回退 VLA 或安全停。

### 4.7 四足映射

| 四足 | 桌面操作 |
|---|---|
| 足端接触估计（无接触传感器） | 夹爪闭合停滞/`g*` |
| 足端滑移检测（非惯性系） | 物体相对夹爪/桌面的位移 |
| 反射恢复（抬脚/减速/改步态） | 开爪/后退/换抓取候选/降速 |
| 本体状态估计（视觉退化） | EE/夹爪/关节历史 dead-reckoning |
| 浮动基座平衡 | 腰/腿/`pivot` 补偿（待验证） |

**边界**：四足是点足/浮动基座；G1 是双足人形 + 平行夹爪。只借方法论，不借具体动力学模型。

### 4.8 伪代码

```python
class GraspMonitor:
    def update(self, obs, cmd, phase):
        g = obs.gripper[self.arm]
        u = cmd.gripper[self.arm]
        self.hist.push(g, u)
        if phase == "CLOSE":
            if self.stalled(self.hist, K=4, eps=self.eps):
                self.g_star = median(self.hist.g[-4:])
                self.u_star = median(self.hist.u[-4:])
                self.success = (self.g_star - self.g_empty > self.delta_g)
                self.conf = sigmoid((self.g_star - self.g_empty - self.delta_g)/self.sigma)
                return "VERIFY", self.success, self.conf
        if phase in ("LIFT", "TRANSPORT"):
            slip = self.visual_slip(obs) or self.width_change(self.hist)
            if slip:
                return "SLIP", False, 1.0
        return phase, None, None
```

### 4.9 失败模式与阈值

| 失败 | 现象 | 处理 |
|---|---|---|
| 空抓 | `g*≈g_empty`，`u_g*≈1` | 换候选/重试 |
| 夹边缘 | `g*` 偏大但物体未随 EE 动 | 视觉确认；换抓取点 |
| 滑移 | `d(t)` 增大 / `g` 突变 | 停止、下降、重抓 |
| 推不动 | `r` 持续大、EE 不动 | 后退/重定位/重规划 |
| 闭合超时 | `g` 长时间不变且 `u` 未到 | 视为堵转/接触，转 VERIFY |
| 传感器噪声 | `g` 抖动 | 多帧中值 + 滞回 |

## 5. 抓取系视觉伺服（GRASP-SERVO）

### 5.1 相机模型

- 腕部：`K_w`（`fx,fy,cx,cy`）、`dist_coeffs`、`inverse_brown_conrady`；先 `cv2.undistort` 再提特征。
- 头部：`K_l,K_r,R,T`、`rectified: true`；用 `cv2.StereoSGBM`/`StereoBM` 或现成双目深度；基线 `b=||T||`，深度 `Z = f b / disparity`。
- 逐任务读取参数，不跨任务写死。

### 5.2 手眼标定

**方法 A：标定板**

```text
固定标定板在 base 系；移动 EE 到 N 个位姿，记录 T_BE_i 和 T_BC_i（相机看板）
求 X = T_CE 满足 A X = X B（OpenCV calibrateHandEye / Tsai-Lenz）
验收：重投影误差 ≤ 5 px；N ≥ 15，覆盖工作空间
```

**方法 B：演示自标定**

```text
成功抓取时，腕部图看到物体/爪；EE 位姿 T_BE_grasp 已知
优化 T_CE，使物体抓取点/爪轴在腕部图的投影与检测一致
目标：min Σ ||π(K_w, T_CE, T_BE_grasp, p_obj) - p_img||²
```

- 方法 B 不需要标定板，但需要足够多的抓取样本和可靠的 2D 检测；可与 A 互补。
- 标定后仍可能有安装/热漂移；用 Broyden 在线修正。

### 5.3 IBVS

归一化坐标 `x=(u-cx)/fx, y=(v-cy)/fy`，点特征交互矩阵：

```text
L = [[-1/Z, 0, x/Z, x y, -(1+x²), y],
     [0, -1/Z, y/Z, 1+y², -x y, -x]]
v_c = -λ L⁺ (s - s*)
```

- 单点只有 2 个约束，6D 速度欠定；用两个点（爪轴两端/物体两个角点）或加深度/姿态正则。
- `Z` 用头部双目/物体先验；未知时用名义深度 + 自适应增益。
- 眼在手上：`v_c = Ad(T_CE) v_e`；若 `T_CE` 不准，用在线 `J = ∂s/∂ξ_e` 的 Broyden 更新：

```text
J_{k+1} = J_k + ((Δs - J_k Δξ) Δξᵀ)/(Δξᵀ Δξ)
Δξ = -λ J_k⁺ (s - s*)
```

- Broyden 对初始 `J` 不敏感；适合最后 1–2 cm。

### 5.4 PBVS

```text
T_BE^d = T_BO · (T_EO*)⁻¹
e = log(T_BE⁻¹ T_BE^d) = [e_pos, e_rot]
v = -λ e
```

- `T_BO` 由头部双目 + ROI 分割/PCA/ICP 估计；透明/反光/变形时降权。
- 对 `T_BO` 做低通/卡尔曼，避免噪声导致抖动。
- 远距离（3–5 cm）用 PBVS；近距离切 IBVS。

### 5.5 混合与切换

```text
c_w = 腕部特征置信度（匹配数/重投影/可见性）
c_h = 头部物体位姿置信度
if c_w > θ_w and object_in_wrist_FOV:
    IBVS
elif c_h > θ_h:
    PBVS
else:
    dead_reckoning (演示轨迹 + EE 历史)
```

- 切换时做目标位姿的平滑过渡（低通/插值），避免跳变。
- 接触段：法向分量缩幅/低通，切向保留；用 `r(t)`/`contact_score` 触发。

### 5.6 前馈 + 反馈与限幅

```text
a_ff = VLA plan[t:t+T_a]
Δa  = servo_correction(e, ė, τ)
a_cmd = a_ff ∘ exp(clip(Δa, ±δ_p, ±δ_r))
```

- `δ_p` 建议 1 cm/步，`δ_r` 0.05 rad/步；按控制频率和任务调。
- 限速/限加速度；工作空间边界；最大重试；异常即停。
- 夹爪闭合/释放单独限速（0.24 s 全行程是上限，实际用更慢）。

### 5.7 延迟补偿

```text
测量 τ = t_action_received - t_obs_timestamp（或 RTT/2）
预测 s(t+τ) ≈ s(t) + \dot s τ（常速）或卡尔曼
e_τ = s(t+τ) - s*
若 τ > T_a/f_ctrl：降增益/增大 T_a/只做 PBVS
```

- 不要假设 RTT 固定；每端口统计 p50/p95/p99。
- 延迟大时，短 T_a 反而可能更不稳；用 G5 扫描。

### 5.8 伪代码

```python
def servo_step(obs, target, arm, tau):
    if wrist_conf(obs, arm) > THETA_W:
        s = wrist_features(obs, arm)
        s_star = target.wrist_features
        e = s - s_star
        J = self.J[arm]
        dxi = -LAMBDA * pinv(J) @ e
        self.J[arm] = broyden_update(J, self.last_dxi[arm], self.last_ds[arm])
        return clip_pose(dxi, DP, DR)
    if head_conf(obs) > THETA_H:
        T_BO = estimate_object_pose(obs)
        T_d = T_BO @ inv(target.T_EO)
        e = log_se3(inv(obs.T_BE[arm]) @ T_d)
        return clip_pose(-LAMBDA * e, DP, DR)
    return dead_reckoning(obs, target)
```

### 5.9 数值稳定与安全

- SE(3) log/exp 用双精度；角度 wrap 到 `(-π,π]`；旋转矩阵正交化。
- 夹爪遮挡/透明：降低 IBVS 权重；不要用不可靠特征硬伺服。
- 碰撞：工作空间/桌面高度/邻近物距离检查；异常时 `SAFE_HOLD`。
- 不要用视觉伺服去“猜”力；没有力传感器，接触靠 `r(t)`/闭合签名/滑移。

## 6. Chunk 调度与系统集成（CHUNK-SCHED + Adapter）

### 6.1 T_a 约束

- `T_a` 在 `metadata` 声明；`example_env.py` 每次校验 `(T_a, ...)`；**提交内固定**。
- `H_plan` 可以大于 `T_a`：VLA 后台产出 30 步 plan；每次 `get_action` 返回下一个 `T_a` 步；新观测到来时用伺服修正。
- 不能在某个相位把 `T_a` 改成 3；只能在提交前选一个 `T_a`，或在 `T_a` 内改变“哪些步是 VLA 原样/伺服修正/保持”。

### 6.2 周期模型

```text
t_cycle = T_a / f_ctrl + τ_infer + τ_net
f_eff   = T_a / t_cycle
```

- 若 `t_cycle > T_a/f_ctrl`，evaluator 可能在 chunk 之间等待；`f_eff < f_ctrl`。
- 小 `T_a`：反馈快，但 `τ_infer` 占比高，可能停顿。
- 大 `T_a`：摊销推理，但开环久，接触任务退化。
- 用单任务通道测 `T_a ∈ {1,3,5,8,15,30}` 的 success/step/latency；选 knee，不选极值。

### 6.3 扫描设计

| T_a | 预期 | 适用 |
|---|---|---|
| 1 | 最快反馈，最高推理开销/停顿风险 | 低速接触、RTT 低 |
| 3–5 | 平衡 | 插入/挂/叠/拉链 |
| 8 | 示例默认 | 通用 |
| 15–30 | 开环久，摊销推理 | 自由空间搬运、抓取前接近 |

- 每档至少 5 次/任务；A/B 同初始条件；记录 p99。
- 如果 `T_a=5` 的 p99 超过阈值，退回 8；不要为了“闭环”牺牲稳定性。

### 6.4 WLA → API adapter

```python
def wla_to_api(wla_action, obs, arm):
    # wla_action: [54] relative EE + gripper + ...
    rel = wla_action[0:6] if arm == "left" else wla_action[13:19]
    T_rel = exp_se3(rel)  # xyz + rotvec
    T_cmd = T_BE_obs[arm] @ T_rel
    xyz, rpy = T_to_xyz_rpy(T_cmd)
    u = map_gripper(wla_action[6] if arm == "left" else wla_action[19])
    return xyz, rpy, u
```

- `T_to_xyz_rpy` 的 rpy 约定必须和 API/数据一致；用一条演示做 round-trip 验证（`rpy → R → rpy`）。
- `map_gripper`：WLA raw scalar → API `[1]`；用数据分布/单任务通道校准；先保守限幅。
- `pivot`：先用中性值/观测值（如 `lower_body` 的腰/腿子集），不要直接映射 WLA 的 base/height；语义未验证。
- 空闲臂：返回观测位姿（保持），夹爪保持当前开合；不要突然归零。

### 6.5 `get_action` 伪代码

```python
def get_action(self, obs):
    self.hist.push(obs)
    phase = self.phase_detector.update(obs)
    target = None
    if phase in ("APPROACH", "ALIGN") and self.arm_busy is None:
        target = retrieve_and_plan(obs, self.task, self.arm)
    if target is None:
        target = self.plan_cache.get(obs, phase)  # non-blocking; VLA 后台刷新
    if target is None:
        return hold_action(obs)                   # 等不到 plan 就保持，不阻塞主循环
    acts = []
    for k in range(self.T_a):
        dxi = servo_step(obs, target, self.arm, self.tau)
        a = compose(target.ff[k], dxi)
        acts.append(to_api(a, obs))
    self.plan_cache.maybe_refresh(obs, phase)
    return {"meta.token": self.token, **stack(acts)}
```

- VLA 推理在后台线程；主线程只做确定性层，保证 p99。
- `phase_detector` 用夹爪/EE/历史；不要依赖 VLA 的隐变量。
- `reset()` 清空历史、相位、plan cache、候选、重试计数、Broyden 的 `J`（或保留标定，清 episode 状态）。

### 6.6 多端口/并发/reset

- 每端口一个进程或一个轻量 endpoint + 共享 GPU 后端；后端要并发，不能串行阻塞。
- 每端口独立 `GraspMonitor`、`ServoController`、`PlanCache`、`GraspLibrary` 查询状态；`reset()` 不能清共享模型。
- 内存：33k 抓取库是只读共享；每端口只存历史/候选索引。
- 日志：每端口单独记录延迟/动作统计，便于定位。

## 7. 实验设计

### 7.1 私有基线

1. **接口基线**：官方 `ExamplePolicy` + `run_server.py`/`run_client.py`，确认 token、shape、`T_a`、`obs_delta_indices`、`image_resize`。
2. **适配基线**：WLA Base（或微调）→ API adapter；`control_space="ee"`；先返回观测位姿保持，确认不报错。
3. **回放基线**：用 HF 数据回放观测，跑相位/抓取库/监测，测离线指标。
4. **单任务基线**：5 个代表任务，每任务 5 次，记录成功/步骤/延迟/失败相位。

### 7.2 指标

| 指标 | 定义 | 用途 |
|---|---|---|
| success | 任务完成 | 主指标 |
| step score | 官方步骤分 | 次指标 |
| first-grasp success | 第一次闭合成功 | 抓取层 |
| grasp verification BA | `(TPR+TNR)/2` | 监测层 |
| slip recall/precision | 滑移检测 | 监测层 |
| servo error | 最终位姿/图像误差 | 伺服层 |
| retry count | 重抓次数 | 稳定性 |
| p50/p95/p99 latency | `get_action` 延迟 | 可信度 |
| jitter | 延迟标准差 | 可信度 |

### 7.3 失败分诊

```text
A 段（抓取）：没对准 / 空抓 / 夹边缘 / 宽度不够 / 碰撞 / 滑落
B 段（最后 3 cm）：插入偏 / 接触力不对 / 物体被移动 / chunk 内看不到 / 释放失败
C 段（语义/长程）：选错物体 / 顺序错 / 超时
```

每个失败打标签；用 `q_t = P(失败在 B 段 | 任务 t)` 和 `g_t = P(失败在 A 段 | 任务 t)` 决定投 GRASP-SERVO 还是 GRASP-PRIOR。

### 7.4 消融矩阵

| ID | VLA | PRIOR | MONITOR | SERVO | T_a | 目的 |
|---|---|---|---|---|---|---|
| A0 | ✓ | – | – | – | 8 | 基线 |
| A1 | ✓ | ✓ | – | – | 8 | 抓取先验单独 |
| A2 | ✓ | – | ✓ | – | 8 | 监测单独 |
| A3 | ✓ | – | – | ✓ | 8 | 伺服单独 |
| A4 | ✓ | ✓ | ✓ | ✓ | 8 | 全量 |
| A5 | ✓ | ✓(无视觉) | ✓ | ✓ | 8 | 视觉检索是否必要 |
| A6 | ✓ | ✓ | ✓ | ✓(绝对目标) | 8 | 相对目标是否必要 |
| A7 | ✓ | ✓ | ✓ | ✓ | 3/5/15/30 | T_a 影响 |

- A5 用任务级固定抓取先验；A6 用绝对位姿目标；对比相对目标。
- 每行在 5 个任务上配对 A/B；每任务 5 次；记录失败相位。

### 7.5 G0–G8

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | 腕部手眼 | 重投影 ≤5 px；ROI 有效 ≥70% | 演示自标定/PBVS 兜底 |
| G1 | 抓取先验 | top-5 可行 ≥80%；位姿误差 ≤5 mm/2° | 任务级固定预抓取 |
| G2 | 抓取判定 | BA ≥90%；误报 ≤5% | 保守重试，不自动判失败 |
| G3 | 滑移检测 | recall ≥80%，延迟 ≤100 ms | 抬升后视觉确认 |
| G4 | 伺服收敛 | 横向 ≤2 mm、深度 ≤3 mm、2 s ≥95% | 降增益/PBVS/加 T_a |
| G5 | T_a 扫描 | 最优优于默认 8/30 | 固定 T_a=5 |
| G6 | 单任务 A/B | 3/5 任务 +10pp；FoldTowel 不回归 >5pp | 不提交 GRASP-EXEC |
| G7 | 人为干扰 | 检测 ≤200 ms；仿真恢复 ≥70% | 只做离线 |
| G8 | 32 任务干跑 | N 端口隔离/reset/内存/p99 ≤150 ms | 回退基线 |

### 7.6 统计与样本量

- 320 trials，`p≈0.25` 时单次标准误 `sqrt(0.25×0.75/320)=2.42pp`；配对设计会低一些，但**不要声称 +1–2pp 是结论**。
- 单任务 5 次 A/B 的置信区间很宽；只做 go/no-go，不做“显著提升”的宣传。
- 用 bootstrap/配对置换；报告 CI，不只报均值。
- 多个任务/多次比较要做多重比较校正，或预注册主指标。

### 7.7 数据划分

- 按 episode/session/物体/背景分组划分，**相邻帧不能跨 split**。
- 抓取库的模板与测试 episode 必须来自不同 session/物体实例；否则离线检索指标虚高。
- 泛化轴：位置/干扰物/背景/未见物品/人为干扰；每一轴单独留出测试。

### 7.8 时间表与资源

| 周 | 工作 | 产出 |
|---|---|---|
| 1 | API adapter、官方 example、回放管线 | 可信基线 + 日志 |
| 2 | 抓取库、相位切分、手眼标定 | GRASP-PRIOR + G0/G1 |
| 3 | 闭合签名、滑移、IBVS/PBVS、T_a 扫描 | PROPRIO + SERVO + G2–G5 |
| 4 | 单任务 A/B、迭代、干跑 | G6–G8 + 提交包 |

- 计算：1×24GB GPU（WLA 推理/微调）；CPU 跑确定性层；存储 0.5–1 TB（关键帧/日志），或按需流式读取 HF。
- 人力：1 人可做；关键是接口/数据管线，不是训练。

## 8. 竞赛策略

### 8.1 任务组合

先验分档（待单任务通道更新）：

- **A 档（抓取+接触杠杆高）**：HangCup、PlugInEthernet、ZipUp、StackBowls、Unlock、ArrangeTestTubes、ToolboxStorage、PlugCharger、PourOutMedicine、SyringeWaterTransfer。
- **B 档（双臂/变形）**：FoldTowel、PackBag、PackDoll、StoreCups、OrganizeStationery、OrganizePencilCase。
- **C 档（语义/分拣）**：FruitSorting、ColorArrangement、OrganizeTools、OrganizeBookshelf。
- C 档不投抓取工程；A/B 档按 `q_t×Δ/cost` 重排。

### 8.2 提交节奏

- 若允许多次提交：先交**安全基线**（官方 WLA + T_a=8 + adapter），锁“更早提交”的 tie-break；再交 GRASP-EXEC。
- 若只允许一次：先用单任务通道把 GRASP-EXEC 打磨到稳定，再交最终版。
- 不要把 320 trials 浪费在“从零训 6B”“完整世界模型”“32 个任务各训一个策略”上。

### 8.3 投入顺序

1. 测量/基线（最高优先级；空榜单下这是唯一可信的起点）。
2. 抓取先验 + 闭合签名（A 段，成本低、可解释）。
3. 腕部手眼 + IBVS（B 段，已有内参，收益直接）。
4. 滑移/反射恢复（人为干扰轴 20%）。
5. T_a 扫描/延迟优化（可信度 + 稳定性）。
6. RTC/REMAC/更大模型（最后，且要过单模型合规）。

### 8.4 不做什么

- 不追空榜单的“榜首差距”；不把 29.7% 当 SOTA。
- 不引入第二个学习模型；不做力/触觉；不做逐任务策略。
- 不在 `pivot` 语义未验证前做全身控制。
- 不用仿真成功率预测真机；仿真只做标定/风洞。

## 9. 风险与合规

**合规分级（提交材料按此写）**：

- **C1（离线资产）**：HF 演示离线挖掘的抓取库/统计量，只读查表，不参与在线学习或梯度更新。
- **C2（确定性控制器）**：相位机、闭合签名、滑移检测、IBVS/PBVS、限幅/重试，无学习权重。
- **C3（同一 checkpoint 编码器）**：若需要视觉特征，只用 VLA 自身冻结 encoder 的前向，不新增、不训练第二个视觉模型。

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定第二个模型 | 先验=查表+几何；监测=信号处理；伺服=控制器；C1/C2/C3 文档 |
| 手眼误差/漂移 | IBVS 偏 | 标定板 + 演示自标定 + Broyden；大误差回退 PBVS |
| 腕部遮挡/透明/反光 | 视觉失败 | 头双目 PBVS、本体 dead-reckoning、闭合签名 |
| 夹爪量纲未知 | 映射错 | 数据分布 + 单任务通道校准；保守限幅 |
| `pivot` 语义未知 | 全身异常 | 中性值；验证；不依赖 |
| 抓取先验 mismatch | 抓错 | 任务/arm/相位过滤；top-k 重打分；低置信回退 |
| 滑移误报 | 频繁重抓 | 滞回/多帧/视觉+本体融合；限重试 |
| 延迟/抖动 | 伺服不稳 | T_a 扫描；RTT 测量；预测；p99 监控 |
| 评测噪声 | 假阳性 | 配对 A/B、bootstrap、CI；320 trials SE≈2.4pp |
| 数据泄漏 | 离线虚高 | 按 episode/session/物体/背景分组；相邻帧不跨 split |
| 安全 | 碰撞/夹手 | 限速/限幅/工作空间/最大重试；异常即停 |
