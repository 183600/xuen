# 第 41 轮 · 二灵感落地 v18：机队编排 × ROS2 运行时契约 × 机队影子共识（「多机即多租户」横切层，四层架构 v6）

> 承接第 40 轮（v17：热预算治理 × 步数感知规划 × 学习-TO 混合轨迹）。本轮灵感词「多机协同 / ROS2」。先给一个可能让人失望、但决定整轮方向的核实结论：官方评测里的 N 台是 **N 个彼此独立的机器人、独立 episode、独立端口**（README §5 原文 “N test robots … each port … its robot”），**不存在单场景内多机器人协作**；N 台唯一真实的「协同」发生在**共享推理后端**（Approach 2）与**跨机队统计**上。同时官方传输是 websockets + msgpack，不是 ROS2（requirements.txt 只有 numpy/msgpack/websockets/Pillow）。因此 v18 拒绝把「多机协同」做成多机器人任务分配/编队/共享地图（那是零测试价值的过度设计），也拒绝把 ROS2 当成官方传输（那会平白增加时延与依赖风险）。**v18 的主轴是：把「多机」正确理解为多租户服务编排，把 ROS2 正确理解为控制面契约而非数据面搬运。**

## 1. 研究者直觉（先直觉与动机，后形式化）

**直觉 1（多机协同 → 官方多机是「N 个独立 episode + 一个共享后端」，不是协作）**。README §5 那句 “each port corresponds to a separate episode on a separate robot” 把问题钉死了：N 台机器人不同场景、不同任务、不同 episode，彼此不共享观测、不共享动作、不共享地图；没有任何接口让机器人 A 影响机器人 B 的任务执行。因此 MRTA（多机器人任务分配）、编队、共享语义地图、跨机器人交接，在本赛道**全部是零测试价值的能力展示**。那「多机」到底剩下什么？剩下两件真实的东西：(a) **共享推理后端**——N 个端口可能同时调用同一模型，调度、批处理、隔离、热与抖动全在这里；(b) **跨机队统计**——N 条独立轨迹构成一个天然样本集，可用于可信度与异常检测。这两件恰好都不是「让机器人协作」，而是「让服务与统计协同」。所以我把本轮第一原则定为：**多机 = 多租户**。

**直觉 2（ROS2 → 控制面契约，不是数据面搬运）**。读完 F67/F68/F73 后我的判断很硬：把 ROS2 放进图像/张量数据面，在 rclpy + DDS 默认配置下几乎必然增加拷贝与抖动，而且官方环境根本不保证装有 ROS2（A46）。但 ROS2 有三样东西是 v17 完全没有的、且正好对官方 §6 的可信度条款：(a) **QoS 的 Deadline/Liveliness/Reliability/History** 把「每步时延平滑、节点活着、动作不丢不乱」变成可声明、可监控的契约；(b) **lifecycle + 发现** 让「恰好 N 个端点、每个端点独立 reset」变成可审计的运行时状态机；(c) **namespace/domain 隔离** 给多租户一个成熟的状态隔离骨架。于是 ROS2 的正确用法是：**官方 websocket 边界一动不动；内部用「ROS2 语义」写控制面契约；数据面保持进程内/共享内存；ROS2 运行时是可选的 L2/L3 档，默认 L1（进程内契约仿真）**。IP 的创新点是契约与合成分析，不是中间件本身。

**直觉 3（接缝：可信度条款是机队级分布性质）**。§6 说的「时延的平滑与稳定」「动作的统计规律性（无异常离群）」不是单步属性，而是**分布属性**：单步快不算平滑，单步正常不算规律。分布属性必须用分布来观测——而 N 台独立机器人正好免费提供一个同任务/同相位的参考分布。于是有了本轮唯一正当的「协同」：**只聚合统计、绝不共享原始状态**的机队共识。它把「多机」从资源负担变成可信度资产：同一任务下某端口的动作统计突然偏离机队参考，就是感知漂移、模型扰动或传感器故障的早期信号。用保形预测给阈值，误报率有分布无关上界（F71），这比拍脑袋设阈值严谨得多。

**直觉 4（共享批处理的隐藏代价：共批非干涉性）**。这是我认为 v17 最大的技术盲点。Approach 2 允许多端口共享一个模型并做批处理；但一旦动态攒批，租户 i 的输出就可能依赖同批里还有谁（kernel 选择、padding、归约顺序、KV/前缀缓存淘汰都会变）。这意味着 **A 机器人的动作会受 B 机器人是否同时在调用影响**——这不只是性能问题，它直接制造 §6 所谓的「动作统计异常离群」，且让结果不可复现。所以「多机协同」在共享后端上必须附加一条硬不变量：**共批非干涉（co-tenant invariance）**——租户 i 的输出在给定自身输入与模型参数下，不随同批集合变化（或变化被严格界定）。落地不是禁止批处理，而是**双车道**：精度关键的插入/放置走「保证道」（独占或固定形状、确定内核），传输类走「弹性道」（动态批处理）。这条不变量是 IP-51/IP-52/IP-53 三者的共同地基。

**直觉 5（修剪即深化：v17 在机队视角下有四项应合并/降级）**。v17 已经背了太多次系统：IP-45 服务网格、IP-25 独立 SLO、IP-46 鲁棒性证书、IP-42 跨本体、IP-26 物理增广、IP-44 三阶段蒸馏，以及 IP-38 的「服务化故障转移」。机队视角一照就清楚：(a) 服务网格与 ROS2 运行时契约是同一件事，合并；(b) 独立 SLO 与机队调度的截止期是同一件事，合并；(c) 鲁棒性证书的主体被运行时契约健康检查吸收，只留低层 CBF 解析证书；(d) 跨本体/物理增广在单一 G1/Dex1 上无测试价值；(e) **跨端口故障转移在物理上不可能**——每个端口是另一台机器人、另一个 episode，A 端口挂了 B 端口无法接管那台机器人的状态，只能做 episode 内恢复。把这条「不可行」明确写出来，也是严谨的一部分。

## 2. 灵感词 → 落地线（新增 + 重构 + 修剪登记）

- 「**多机协同**」→ **IP-51 FLEET-ORCHESTRATOR（P0 新增）**：租户/作业模型 + **分数感知价值密度调度**（用 IP-49 的 E_score 当价值信号）+ EDF 准入（含非抢占阻塞项）+ **双车道**（保证道/弹性道）+ **抖动感知 goodput** + 公平/防饥饿（WFQ+老化）+ **共批非干涉性** + 每租户状态隔离 + 失败记忆的机队聚合（只聚合签名）。
- 「**ROS2**」→ **IP-52 ROS2-RUNTIME-CONTRACT（P0 新增，重构 IP-45/25/46）**：官方 websocket 边界不变；内部声明式运行时契约（rate/deadline/jitter/QoS/state_scope/degrade）+ 契约合成与响应时间分析（RTA）+ **四级运行时阶梯**（L0 进程内 / L1 契约仿真 / L2 rclpy / L3 rclcpp composition+零拷贝）+ lifecycle 管理恰好 N 个端点 + domain/namespace 隔离。
- 「**接缝（可信度）**」→ **IP-53 FLEET-SHADOW-CONSENSUS（P0 新增）**：每租户轻量影子预测器（异步、按风险阻塞）+ 同任务机队统计参考 + Mahalanobis 异常分 + **保形/ACI 阈值**（分布无关 FPR）+ 只聚合统计的跨租户失败记忆 + 异常时降级路由。
- 合并/修剪：**IP-45 → 并入 IP-52**（ROS2 运行时就是服务网格，不建两套）；**IP-25 → 并入 IP-51**（per-tenant deadline + 机队抖动）；**IP-46 主体 → IP-52 运行时健康**，仅保留低层 CBF/收缩证书；**IP-42 → P2**（单一 G1/Dex1，无测试价值）；**IP-26 → P2**（URDF 未核实 A17，32 数据集已覆盖多样性）；**IP-44 → P1**（保留 LoRA+RARA）；**IP-38 去掉跨端口故障转移**（物理不可行），仅保留 episode 内恢复。
- 升级：**IP-48**（从单租户热 governor 升级为 IP-51 的热约束子模块）；**IP-49**（E_score/value 直接供 IP-51 调度）；**IP-24**（失败签名 + 机队异常信号）；**IP-21**（旗舰 = 机队运行时 + 单模型多租户）；**IP-33 CBF** 不变（最低优先级兜底）；IP-2/3/4/9/10 继承。

## 3. 形式化直觉（严格版见产物区 §5）

**定义 34（租户/作业与机队）**：租户 `i` 对应 `(p_i, e_i, κ_i)`（端口、episode、reset 计数）；作业 `J_i=(τ_i, φ_i, d_i, b_i, V_i)`，其中 `τ_i` 为任务、`φ_i` 为相位、`d_i` 为当前 chunk 截止期（= `T_a·control_period − 安全裕量`）、`b_i∈B` 为服务档位（模型分支/分辨率/TO 开关）、`V_i` 为价值估计。机队状态 `F_t={J_i}`。**关键事实（P64）**：榜单是 episode 的平均 ⇒ 总目标是各 episode 得分之和，机队调度是在**可分离目标**上做资源聚合，不需要（也不允许）跨 episode 的任务协作。

**定义 35（抖动感知机队调度）**：每个调度 epoch 选择 `x_i∈{0,1}` 与档位 `b_i`，求解
`max_x Σ_i x_i·V_i(b_i)  s.t.  Σ_i x_i·c_i(b_i) ≤ C_t； s_i ≥ c_i(b_i)+B_max； H_gpu ≤ H_max； Jain(x) ≥ J_min； Var(L) ≤ V_max`，
其中 `s_i=d_i−(now+remaining_i)` 为松弛、`c_i` 为预测算力、`B_max` 为非抢占阻塞上界、`Jain` 为公平指数。价值密度 `ρ_i=V_i(b_i)/c_i(b_i)`，在线用「价值密度 + EDF 可行性」贪心，并做阶段重解。目标量 `G=Σ_i 1[L_i≤d_i]V_i − λ·Var(L)` 记为**抖动感知 goodput**：它同时惩罚超时与抖动，正好对应官方 §6。

**定义 36（共批非干涉与状态隔离）**：设租户 `i` 的输出 `y_i=f(x_i,θ,B)`，`B` 为同批集合。**共批非干涉**要求对所有含 `i` 的 `B,B'`：`‖f(x_i,θ,B)−f(x_i,θ,B')‖ ≤ ε`（保证道要求 `ε=0`）。**状态隔离**要求任何可变状态的键含 `tenant=(p,e,κ)`，`reset` 将该键下状态清零；只允许共享**只读**前缀（系统提示、静态模型权重）。二者共同定义「多机共享后端」的正确性边界。

**定义 37（ROS2 运行时契约）**：节点 `n` 的契约 `C_n=(rate, deadline D_n, jitter J_n, qos, state_scope, degrade)`；图合成 `C=⊕_n C_n`，端到端截止期 `D_end=Σ_n(D_n+J_n)+Σ_transport`，可行当 `D_end ≤ T_a·control_period`。`qos` 采用 ROS2 语义（Reliability/Durability/History/Depth/Deadline/Liveliness/Lifespan，F68）。运行时阶梯 `L0⊂L1⊂L2⊂L3`，默认 L1，只有 E74 实测优于基线才升到 L2/L3。

**定义 38（机队保形共识）**：对同任务/相位簇 `c`，动作统计 `ψ_i=Ψ(chunk_i)`（如关节增量范数、jerk、夹爪时序、EE 位移），参考 `(μ_c,Σ_c)`，异常分 `s_i=(ψ_i−μ_c)^TΣ_c^{-1}(ψ_i−μ_c)`；阈值 `q_c` 取校准集 `(1−α)` 分位。**保形保证**：若校准与在线同分布（可交换），`P(s_new>q_c)≤α`；用 ACI 在线更新 `α_{t+1}=α_t+γ(α−err_t)` 可在分布漂移下维持长期误报率。**跨租户只聚合 `ψ` 的统计量与失败签名计数，绝不上传原始观测/动作轨迹**。

**命题速览**：P60（EDF+准入：`U+B_max/C≤1` 下无截止期错过）；P61（价值密度反例：FIFO 会为低价值长作业牺牲高价值短作业，价值密度+EDF 可同时满足）；P62（共批非干涉的充分条件：固定形状+确定内核+无跨请求可变缓存；动态批处理一般不满足）；P63（保形 FPR 上界 + ACI 长期保证）；P64（榜单可分离 ⇒ 机队调度直接优化排名量）；P65（状态隔离归纳：无可变共享路径 ⇒ 无污染）。

## 4. 关键决断

1. **多机即多租户**：不造多机器人协作；官方 N 机是 N 个独立 episode，唯一耦合是共享后端与机队统计。
2. **排名可分 ⇒ 调度即分数聚合**：用 IP-49 的 E_score 当价值，价值密度 + EDF 准入 + 抖动惩罚，而不是 FIFO/纯热阈值。
3. **双车道 + 共批非干涉**：精度关键（插入/放置/双臂交接）走保证道（独占/固定形状/确定内核）；传输类走弹性道（动态批）。这是硬不变量，不是性能优化。
4. **ROS2 只做控制面契约**：websocket 边界不动；数据面进程内/共享内存；ROS2 运行时可选（L2/L3），默认 L1；`requirements.txt` 不引入 ROS2 硬依赖。
5. **机队冗余用于可信度**：只聚合统计的保形共识；异常触发降级重规划，不共享原始状态。
6. **修剪四项 + 删除跨端口 failover**：服务网格/SLO/证书主体合并，跨本体/物理增广降 P2；跨端口接管物理不可行。

## 5. 本轮最大风险（一句话）

**若 N 机并发的真实瓶颈只是 GPU 算力而非调度/抖动、若 ROS2/DDS 的任何运行时档都打不过进程内基线、若同任务同相位的机队样本太稀疏使保形阈值失效——「机队编排-运行时契约-影子共识」会退化为三个只在纸面上成立的机制；必须以 E73（机队调度）+ E74（运行时 A/B）+ E75（共批非干涉/隔离）+ E76（保形共识）+ E77（QoS 契约合成）+ E78（端到端）六重守门，按「调度 > 契约 > 共识」优先序保底，全败即回退 v17 单租户架构。**

## 5. 重点展开

### 5.1 IP-51 FLEET-ORCHESTRATOR（机队编排，完整设计）

**IP 卡片（六字段）**
- **动机**：F60 §5 允许 N 端口共享后端且并发调用、要求状态隔离；§6 把时延稳定性与动作规律性计入可信度；榜单是 episode 平均（F59），故总目标是可分离的分数聚合。v17 的 IP-48 只有「热阈值 + 队列」，会让低价值长作业饿死高价值精度作业，也会在动态攒批时引入跨租户数值干扰（直觉 4）。
- **与现有方案差异**：LLM 服务调度（F69）优化吞吐/goodput，不关心「每步动作统计规律」与「共批非干涉」；机器人实时调度（F70）通常单任务、无多租户价值。我们把 **IP-49 的 E_score 当价值**，把**抖动与共批非干涉当硬约束**，把**步骤/热预算当资源**，形成「分数感知 + 抖动感知」的双目标调度。
- **技术可行性**：租户数 N 由官方公布（A36，当前未知，按 {1,3,8} 参数化）；每个 chunk 窗口重解一次，决策变量≤N×|B|，N 小、|B|≤4，枚举/贪心毫秒级；价值估计直接复用 IP-49 的 E_score 与相位；隔离用键空间与 reset 审计，零额外模型。
- **所需资源**：GPU 遥测（pynvml）；每租户状态容器；一个轻量调度器线程；机队失败记忆（SQLite/内存表）；无新增大模型。
- **落地步骤**：① 定义租户/作业结构与价值估计；② 实现 EDF 准入 + 价值密度贪心 + WFQ/老化；③ 双车道与共批非干涉执行器；④ 接 IP-48 热约束与 IP-52 契约；⑤ 接 IP-53 异常信号；⑥ E73/E75/E78 验收。
- **风险**：算力不是瓶颈（→E73 证伪即退回 EDF）；价值估计偏差（→用 E_score 下置信界 + 在线校准）；保证道独占导致 GPU 利用率低（→只在精度关键相位开启，其余弹性）；共批实现复杂（→固定形状 padding 的保守实现）。

**符号表**

| 符号 | 含义 | 来源 |
|---|---|---|
| `i=(p,e,κ)` | 租户：端口/ episode / reset 计数 | F60 §5 |
| `J_i=(τ,φ,d,b,V)` | 作业：任务/相位/截止期/档位/价值 | 定义 34 |
| `c_i(b)` | 预测算力（ms） | 遥测 + 剖析 |
| `s_i` | 松弛 `d_i−(now+remaining)` | 定义 35 |
| `B_max` | 非抢占阻塞上界 | 实测 |
| `ρ_i=V_i/c_i` | 价值密度 | 定义 35 |
| `G` | 抖动感知 goodput | 定义 35 |
| `lane∈{guaranteed,elastic}` | 保证道/弹性道 | 定义 36 |

**目标与算法（伪代码）**
```
每 chunk 窗口 / 每 100ms：
  1. 更新作业：τ,φ ← IP-49/28v2；d_i ← T_a·period − safety；
     V_i(b) ← IP-49 的 ΔE_score·value_weight(φ)（精度相位↑）
  2. 价值密度排序 ρ_i = V_i(b_i)/c_i(b_i)
  3. 准入（EDF 可行性）：
     for job in 按 ρ 降序:
        if s_i ≥ c_i(b) + B_max and U + c_i/C ≤ 1−ε and H_gpu ≤ H_max:
            admit(job); U += c_i/C
        else:
            b_i ← degrade_once(b)          # 轻分支/降分辨率/关 TO
            若仍不可行 → 推迟到下一窗口（不丢 episode）
  4. 车道分配：
     if φ ∈ {insert, place, bimanual_handover} or V 高: lane=guaranteed
        → 独占/固定形状/确定内核/禁动态攒批
     else: lane=elastic → 允许 continuous batching（F69）
  5. 公平与防饥饿：WFQ 权重 + 老化（等待>2 窗口的作业 ρ 提升）
  6. 输出 schedule → IP-52 运行时按契约执行
  7. 记账：L_i, S_used, H_gpu, H_motor → 回报 IP-48/IP-49
```
**双车道表**

| 维度 | 保证道（guaranteed） | 弹性道（elastic） |
|---|---|---|
| 适用相位 | 插入/放置/双臂交接/高价值 | 接近/运输/退避/低价值 |
| 批处理 | 独占或固定形状 padding | 动态 continuous batching |
| 内核 | 确定内核、固定 reduction 顺序 | 允许 autotune/动态 kernel |
| 抖动目标 | p99 ≤ d_i，Var 最小 | 吞吐优先，p99 软约束 |
| 降级 | 宁可降档也不 miss | 宁可排队也不浪费算力 |

**正确性论证**
- **P60（EDF+准入无错过）**：可抢占单资源下 EDF 在 `U≤1` 可行（Liu & Layland 1973）；非抢占 chunk 引入最大阻塞 `B_max`，故充分条件 `U+B_max/C≤1`；准入只接受满足该式与松弛的作业，因此已准入作业在模型准确时不会 miss。模型误差由安全裕量与降档吸收。
- **P61（价值密度优于 FIFO）**：构造反例——租户 A：`c=80ms, V=10, d=200ms`；租户 B：`c=30ms, V=100, d=100ms`；`C=100ms`。FIFO 先 A 后 B：B 在 110ms 完成 >100ms，错过；价值密度先 B（30ms）再 A（110ms）：两者均满足，总价值 110>10。故在同等算力下，价值密度+EDF 的可行价值集合严格包含 FIFO 的可行集。
- **P62（共批非干涉充分条件）**：若 (i) 批形状固定（padding 到常量）、(ii) 内核确定且 reduction 顺序与批组成无关、(iii) 无跨请求可变缓存（KV 仅按租户键）、(iv) 每租户 RNG 独立，则 `f(x_i,θ,B)` 与 `B\i` 无关。反之，动态形状/autotune/前缀缓存跨租户淘汰会破坏该性质（E75 专测）。
- **P64（榜单可分离）**：榜单按 episode 平均 ⇒ `Score=(1/M)Σ_m(α·success_m+β·stepscore_m)`；故最大化 `Σ_i x_i V_i` 与最大化排名量同向（在 `V_i` 为边际得分时），机队调度无需跨 episode 协作。这是本轮框架成立的前提。
- **复杂度**：排序 O(N log N)，准入 O(N)，车道分配 O(N)；N≤8 时 <1ms。

### 5.2 IP-52 ROS2-RUNTIME-CONTRACT（运行时契约，完整设计）

**IP 卡片（六字段）**
- **动机**：F60 §6 的「时延平滑、动作规律」需要可声明、可监控的运行时约束；F67/F68 提供 QoS 语义与发现/生命周期；F73 证明 ROS2 不能是硬依赖。v17 的 IP-45/25/46 各说各话，没有统一的运行时契约。
- **与现有方案差异**：不是「用 ROS2 重写系统」，而是**把 ROS2 的 QoS 语义抽象成与中间件无关的契约 DSL**，再用四级运行时阶梯按实测选择。它把「服务网格 + SLO + 鲁棒性证书」三件事收敛成一个可检查、可降级、可审计的对象。
- **技术可行性**：契约检查是静态图 + 运行时监控，纯 Python 可实现（L1）；ROS2 适配器（L2/L3）可选，依赖隔离在可选包；恰好 N 端点由 supervisor 管理（启动 N 个 worker，健康检查，端口与 tenant 一一绑定）；domain/namespace 隔离在 ROS2 档用 `ROS_DOMAIN_ID`/namespace，在 L1 档用进程/键空间。
- **所需资源**：一个契约注册表；一个 supervisor；pynvml；可选 rclcpp/rclpy 环境（A46 风险）；无新模型。
- **落地步骤**：① 定义契约 schema（rate/deadline/jitter/QoS/state_scope/degrade）；② 实现契约检查与 RTA 合成；③ 实现 L0/L1（默认）；④ 可选 L2/L3 适配器；⑤ supervisor 恰好 N 端点 + reset 审计；⑥ E74/E77 验收。
- **风险**：ROS2 环境不可用/版本漂移（→L0/L1 默认，适配器隔离）；DDS 默认发现引入广播风暴与端口冲突（→domain_id/静态 peer/共享内存，E74 压测）；契约过于形式化拖慢启动（→静态检查一次，运行时只监控关键量）；L2/L3 实测更差（→保持 L1，契约仍有效）。

**契约 schema**
```
Contract = {
  name,                    # 节点名
  in_topics/out_topics,    # 数据面（可绕过 DDS）
  rate_hz,                 # 期望频率
  deadline_ms,             # 端到端预算（映射 get_action 的 chunk 窗口）
  jitter_ms,               # 允许抖动（映射官方 §6）
  qos: {reliability, durability, history, depth, liveliness, lease_ms},
  state_scope: {tenant|global, reset_on_episode: bool, key},
  degrade: [ordered actions]   # 超预算时按序降级
}
```
**合成与响应时间分析（RTA）**
```
D_end = Σ_{n∈graph}(D_n + J_n) + Σ_{e∈edges} transport_e
feasible(C) ⇔ D_end ≤ T_a · control_period − safety_margin
             ∧ ∀n: state_scope 合法
             ∧ exactly_one_tenant_key(n)
```
**四级运行时阶梯**

| 档 | 数据面 | 控制面 | 预期 | 采用条件 |
|---|---|---|---|---|
| L0 | 进程内直调 | 无 | 基线，最低抖动 | 永远可用 |
| L1 | 进程内/共享内存 | 契约监控（deadline/liveliness 仿真） | **默认** | E74 不劣于 L0 |
| L2 | rclpy 节点 | ROS2 QoS/lifecycle | 中 | 仅在控制面复杂度收益 > DDS 开销 |
| L3 | rclcpp composition + 零拷贝 | ROS2 QoS/lifecycle | 低时延（若 C++/共享内存） | E74 实测 p99 抖动↓≥20% |

**官方要求 → 契约机制映射**

| 官方要求（F60） | 契约机制 | ROS2 档的 QoS（L2/L3） |
|---|---|---|
| 每步时延平滑稳定 | per-request deadline + 准入 + 保证道固定形状 | `Deadline`、`Liveliness` |
| 动作统计规律、无离群 | 共批非干涉 + IP-53 保形监控 | `History=Keep last`、`Reliability` |
| N 端口并发 | 租户键 + 调度器 | 独立 context/`ROS_DOMAIN_ID` |
| reset/历史隔离 | `state_scope` + reset 审计 | `Durability=Volatile`（静态配置才 Transient local） |
| 恰好 N 个端点 | supervisor 启停 + 健康检查 | lifecycle nodes |
| token 每步校验 | websocket bridge 前后校验 | n/a（边界外） |

**算法（supervisor + 契约检查）**
```
启动：
  N ← expected_ports()                      # 官方公布；自检失败即报警
  for p in range(8765, 8765+N):
     tenant[p] = new_tenant(p)
     检查 metadata/契约兼容；启动 worker（L1/L2/L3 按 E74 配置）
     端口自检：握手 + 空 action + token
运行：
  每 100ms：contract_monitor 收集 L_i/J_i/state_key
  若 D_end 预测超预算：触发 degrade（先保证道降档，再弹性道排队）
  若节点 liveliness 超时：重启该 worker，state 清零并记 reset 审计
  若端口数≠N：拒绝启动（官方明确要求精确相等）
```
**正确性论证**
- **P66（契约可行性 ⇒ 端到端预算）**：若每个节点满足自身 `D_n+J_n` 且传输延迟上界为 `transport_e`，则串行图端到端上界为求和；故 `D_end≤chunk窗口` 时，get_action 在窗口内完成。该结论依赖上界准确，故 E77 用实测校准。
- **P67（隔离可审计）**：`state_scope` 强制每可变键含 tenant；supervisor 在 reset 时清零并写审计；因此任意时刻租户状态只被其端口访问，满足定义 36 的隔离部分。
- **P68（ROS2 非必需）**：L0/L1 不依赖任何 ROS2 组件，故 A46 不构成阻塞；L2/L3 是可选加速/治理档，失败不影响基线。这使方案对官方依赖清单保持合规。

### 5.3 IP-53 FLEET-SHADOW-CONSENSUS（机队影子共识，完整设计）

**IP 卡片（六字段）**
- **动机**：F60 §6 把「动作统计规律性」写进可信度；N 台独立机器人提供同任务/相位的天然参考分布；v17 的 IP-24 只在单 episode 内看失败，无法利用机队冗余。影子预测则给「动作发出前」一个低成本的可行性/异常检查。
- **与现有方案差异**：不是跨机器人共享状态（禁止），也不是集中式数字孪生（太重）；是**每租户异步影子 + 只传统计量的机队共识**。用保形预测给误报控制，用 ACI 处理分布漂移；这是把「多机」变成可信度资产的唯一安全方式。
- **技术可行性**：影子可用轻量一步预测器（学习动力学或 MuJoCo 短程 rollout），异步执行，deadline 内只在风险高时阻塞；统计量维度低（~10 维），Mahalanobis 毫秒级；保形校准用已有 episode/自采数据；失败记忆只存 `(task, signature)` 计数。
- **所需资源**：IP-35 MuJoCo 沙箱或轻量学习模型；每任务校准集（公开 32 数据集 + 自采）；统计量缓存；无新增大模型。
- **落地步骤**：① 定义动作统计 `Ψ`（关节增量/EE 位移/jerk/夹爪时序）；② 训练/接入影子预测器；③ 建立每任务/相位参考与保形阈值；④ ACI 在线更新；⑤ 接 IP-24 失败签名与 IP-51 降级路由；⑥ E76/E78 验收。
- **风险**：同任务并发稀疏（→按任务族/相位分层聚类；仍稀疏则退回影子单租户）；影子保真度低（→只用于风险排序，不直接否决；高不确定性交 IP-50/MuJoCo）；保形可交换性被破坏（→ACI + 定期重校准）；额外算力（→异步 + 低风险不阻塞）。

**符号表**

| 符号 | 含义 | 来源 |
|---|---|---|
| `Ψ(chunk)` | 动作统计（增量范数/EE 位移/jerk/夹爪时序） | 设计 |
| `c=(τ,φ)` | 任务/相位簇 | IP-49/28v2 |
| `(μ_c,Σ_c)` | 机队参考（稳健在线更新） | 机队 |
| `s_i` | Mahalanobis 异常分 | 定义 38 |
| `q_c` | 保形阈值（(1−α) 分位） | 校准集 |
| `α_t` | ACI 在线误报率 | Gibbs & Candès 2021 |
| `M_f[(τ,sig)]` | 机队失败签名计数（仅聚合） | IP-24 |

**算法（影子 + 保形共识）**
```
每 chunk 产生后（异步）：
  1. 统计：ψ_i = Ψ(chunk_i)
  2. 影子：ô_{t+1}, r_i = Shadow.predict(obs_t, chunk_i)
     risk_i = r_i + w·1[ô 与预测偏离 > θ_shadow]
  3. 机队共识（仅同 c=(τ,φ) 且样本≥n_min）：
       s_i = (ψ_i−μ_c)^T Σ_c^{-1} (ψ_i−μ_c)
       若 s_i > q_c 或 risk_i > θ_high：
           flag_i = True
           M_f[(τ, sig_i)] += 1          # sig_i 由 IP-24 分类
  4. 路由（仅在有松弛时阻塞）：
       flag → IP-51 降档/换保证道；IP-49 软重规划；必要时 IP-50 重解
     否则：仅记录，不阻塞返回
  5. ACI 更新：err = 1[flag ∧ 真故障]；α_{t+1}=α_t+γ(α−err)
  6. 参考更新：稳健均值/协方差（裁剪 + 遗忘因子），并按 task 隔离
```
**正确性论证**
- **P63（保形 FPR）**：若校准分与在线分可交换，则 `P(s_{new}>q_c)=α`（有限样本下 `≤α` 的边际覆盖）；ACI 将 `α_t` 在线调整，长期误报率 `→α`，在分布漂移下仍受控（Gibbs & Candès 2021）。因此「机队异常」不是拍脑袋阈值，而是有分布无关保证的告警。
- **P69（只聚合不泄状态）**：算法只向机队上传 `ψ` 的统计量与 `(τ,sig)` 计数，从不上传 `obs`/`chunk`/状态轨迹；即使统计量被其他租户读取，也不构成 episode 状态污染（定义 36）。跨租户可用的仅是「任务级先验」，不改变单租户输出的可复现性。
- **P70（异常→降级不劣化）**：`flag` 只触发降档/重规划，而 IP-33 CBF 与 v17 保底路径仍在；最坏情况退化为 v17 的单租户执行，故不劣于基线。
- **复杂度**：`Ψ` O(d)，Mahalanobis O(d²)（d≈10），影子异步；主路径额外 <1ms（不含影子）。

### 5.5 训练/服务伪代码（v18 增量版）

```python
# ===== 离线：价值先验与机队参考 =====
def build_fleet_priors(data):
    p_s = bayesian_smoothed_success_rate(data, dims=[skill, scenario])
    refs = {c: robust_mean_cov(extract_action_stats(data, c))
            for c in cluster_keys(data)}            # IP-53：按任务/相位
    q_c = {c: conformal_quantile(scores(refs[c]), alpha=0.05) for c in refs}
    return p_s, refs, q_c

# ===== 运行期：机队编排主循环（每个 worker/端口独立调用，共享后端共享模型）=====
def act_v18(tenant, obs, state):
    # 1. 作业更新（租户私有状态；键含 tenant）
    state.update(obs, tenant.key)
    job = Job(tenant, task=state.task, phase=state.phase,
              deadline=state.chunk_window - SAFETY,
              value=state.plan.expected_score_gain(obs))

    # 2. 机队调度（共享后端；价值密度 + EDF 准入 + 双车道）
    sched = fleet_orchestrator.admit_and_assign(job, fleet_state,
                                               thermal=ip48.ledger())
    if sched.lane == "guaranteed":
        # 保证道：固定形状/确定内核/禁动态攒批（共批非干涉）
        chunk = model.infer_fixed_shape(obs, tenant_key=tenant.key)
    else:
        # 弹性道：允许 continuous batching（F69）
        chunk = model.infer_batched(obs, tenant_key=tenant.key)

    # 3. 契约执行（L1 默认；L2/L3 可选）
    with runtime_contract(tenant, deadline=job.deadline, jitter=J_MAX,
                          state_scope=tenant.key) as rc:
        chunk = ip50_refine_if_needed(chunk, state, sched.budget)
        if not ip33_cbf_check(chunk):
            chunk = resample_or_fallback(state, r=2)
    # 4. 影子 + 机队共识（异步；异常才阻塞/降级）
    risk = ip53.shadow_risk(obs, chunk)
    flag = ip53.consensus_flag(tenant, state.task, state.phase, chunk)
    if (risk > THETA_HIGH or flag) and sched.slack_ok:
        state.need_plan = True
        chunk = fleet_orchestrator.degrade(tenant, chunk)
    # 5. 记账与返回
    ip48.charge(tenant.key, chunk, job.value)
    return adapt(chunk, control_space=tenant.control_space)

# ===== 共享后端：租户隔离与 reset 审计 =====
def reset(tenant):
    for k in state_store.keys_owned_by(tenant.key):
        state_store.clear(k)                # 含 memory/planner/RNG/shadows
    rng[tenant.key] = new_rng(seed=tenant.key)
    audit.append(("reset", tenant.key, monotonic()))
    assert no_shared_mutable_state(tenant.key)   # 隔离不变量（E75）
```

| E56–E72 | 沿用 v15–v17 | — | — |

**降级机制 v5（按「调度 > 契约 > 共识」优先序）**
- **E73 失败**（调度无增益）→ 退回 EDF + per-tenant 热阈值（v17 IP-48），关闭价值密度与双车道。
- **E74 失败**（ROS2/契约运行时更差）→ 固定 L0 进程内；契约仅保留为静态文档与监控，不参与执行。
- **E75 失败**（共批非干涉无法保证）→ 采用官方 **Approach 1：每端口独立进程**（放弃共享后端的显存收益），或所有相位走保证道；隔离优先于吞吐。
- **E76 失败**（机队共识无检测力）→ 关闭共识，仅保留单租户影子（高风险才阻塞）；失败记忆不跨租户。
- **E77 失败**（RTA 预测不可信）→ 用静态优先级 + 实测阈值 + 保守准入；契约缩为 deadline 监控。
- **A46 ROS2 不可用** → 直接 L0/L1，不影响其余机制。
- **六项守门全败 → 整体回退 v17 单租户架构（保留 IP-48/49/50 三线）。**

## 8. 清单迭代规则（继承 27–56 + 本轮新增 57–61）

- 继承规则 27–56（通道诚实/映射验证/SLO/fail-safe/灵感-现实校验/单模型合规/步骤分双解释/稠密监督/方法论遗产/元数据重照亮/语言口径分离/摊销/验证器分级/灵感词落地/层级联合规划/跨本体运动/流式韵律/渐进蒸馏/服务化/证书化/组合代数/热预算/期望得分/学习-TO/修剪优先/热预算一等公民/期望得分规划/学习-TO 三段式/修剪优先/上下文即信念/任务导向抓取/接触契约/不确定即投资/数据公开=少建）。
- **57（新增）：多机=多租户原则**——官方多机是 N 个独立 episode；任何「机器人间协作」若不在评测接口内，一律不做；多机相关工作只允许落在共享后端的调度/隔离/统计上。
- **58（新增）：控制面/数据面分离原则**——官方 websocket 边界不动；ROS2/QoS 只做控制面契约；数据面优先进程内/共享内存；ROS2 不得成为硬依赖（F73）。
- **59（新增）：共批非干涉原则**——共享后端必须保证租户输出不随同批集合变化（保证道精确，弹性道有界）；这是可信度条款（F60 §6）的运行时不变量，不是性能选项。
- **60（新增）：只聚合统计原则**——跨租户只允许传递动作统计量、失败签名计数与任务级先验；禁止传递原始观测/动作/状态轨迹，保证状态隔离可审计。
- **61（新增）：不为未评测能力付费原则**（强化 29/51）——灵感词必须先做「官方是否评测」校验；不在评测接口内的能力（多机器人协作/编队/MRTA/ROS2 传输）直接拒绝或 P2；每轮新增必须伴随合并或删除。

**本轮最大风险一句话**：N 机并发的真实瓶颈若只是 GPU 算力、ROS2/DDS 若始终打不过进程内基线、同任务机队样本若太稀疏——「机队编排-运行时契约-影子共识」就会退化成三个纸面机制；E73–E78 六重守门按「调度 > 契约 > 共识」保底，全败即回退 v17 单租户架构。

**当前最值得押注**：**IP-51 FLEET-ORCHESTRATOR（机队编排）**——它是本轮唯一直接优化「榜单可分离总分」且只在官方真实耦合点（共享后端并发）上发力的 IP；价值密度+EDF+双车道可被 E73/E75 两个实验快速证实或证伪，且不需要新模型。IP-52 为它提供可审计的运行时约束，IP-53 把机队冗余转成可信度；若只保留一条新线，就保留它。
