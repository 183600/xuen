# 第 1 轮 · 想法区

## 1. 两个灵感词先撞一下

- **动作分块**：人类抓取不是每 10ms 重新决策，而是把「伸手—对位—闭合」打包成一个动作单元，开环执行完再根据新观测重规划。它把「决策频率」与「控制频率」解耦。
- **最小可行产品**：先做一个能跑通的极薄垂直切片，用真实反馈尽早证伪核心假设，而不是先把九个证书模块全部造齐。它的技术含义还包括：找到「能保持全部承诺的最小单元」。
- **撞点**：**验证也可以分块**。现有 HPC-E+ 在 50Hz 控制环上逐步签发证书，等于把「验证频率」绑死在「控制频率」上。如果动作已经分块，那么最小可行的验证单元也应是一个 chunk，而不是单步动作。MVP 在这里不是「少做功能」，而是「找到能保持安全/合规/能量全部承诺的最小验证粒度」。

## 2. 核心研究命题：ACCT

提出 **ACCT（Action-Chunk Certificate Tube，动作块证书管）**：把证书从「单步动作」上移到「动作块」。一次生成、签名、复核一张 Chunk Certificate，覆盖整段可达状态管（reachable tube）；块内开环执行，块边界重规划，并把未完成的义务（obligation）携带到下一块。

三个可证伪假设：

- **H1（摊销有效）**：在管可靠的前提下，块级验证的每步开销随 H 近似 `c_tube + c_cert/H` 下降，而安全违规率不高于逐步证书。
- **H2（边界是主风险）**：块级方案的安全违规主要发生在块边界与义务跨块处，而非块内部。
- **H3（MVP 切片先证伪）**：一个「单相机 + 单机械臂 + 单条禁入义务」的垂直切片，能在早期暴露管模型误差与义务携带错误；而全模块构建要晚得多才暴露。

## 3. 与既有 v23 框架的接缝

- 不推翻 IP-431..439。ACCT 是**计划层**的宏动作证书，挂在 HPC-E+ 的 `admits` 之前/之内。
- **CESC** 负责块级版本一致性（一张块证书绑定一个版本五元组）。
- **FSVC** 的 conformal 从「单帧」升级为「整条轨迹的非一致性分数」，天然给出**整块覆盖**（无需对 H 步做 Bonferroni 并集放大）。
- **IPAM** 只对 chunk 证书生成器与管传播器打标，MVP 阶段不生成完整权利要求。
- 新执行集：`Exec_v24 = Exec_v23 ∩ {块证书可签发且最小可行前缀非空}`，仍是子集，单调链不破。

## 4. MVP 纪律：本轮刻意不做

- 不做多机器人 CFC+++ 跨层仲裁（先单机）。
- 不做接触丰富操作的管传播（先准静态 + 有界扰动）。
- 不做完整 IP 权利要求生成（只打标）。
- 理由：这些都不是验证「块级证书是否成立」的最小必要件。先把最薄的一条端到端链路跑通。

## 5. 关键开放问题

- **Q1 管保守度**：H 增大时 zonotope 膨胀，可能出现「无可行块」→ 可用性崩塌。能否用数据驱动的 conformal 管半径替代纯区间？
- **Q2 义务跨块**：deadline 落在块内 vs 跨块，残差义务如何形式化，并证明跨块的归纳不变式？
- **Q3 最小可行前缀**：如何在「够推进任务」与「留足重规划余量」之间定义可证且不抖动（chattering）的阈值？
- **Q4 块间缝隙**：重规划从实测状态出发，是否需要块间重叠（overlap）来保证不存在「无证书缝隙」？

## 6. 下一步

先把 ACCT 的谓词与定理写死（见产物区），再做 2D 仿真的 MVE：H∈{1,5,10,20}，对比逐步证书，测验证开销 / 违规率 / 任务成功率 / 边界回退率。

## 7. 本轮最大风险（一句话）

动作块的「管」若因接触或未建模动力学被低估，块级证书会把一个危险的中间动作藏进看似安全的整块里——即**管近似的可靠性直接决定块级验证是「安全摊销」还是「风险打包」**。

# 第 1 轮 · 产物区：ACCT — 动作块证书管

> 目标：在不推翻 v23 四证体系的前提下，把证书的验证粒度从「单步」提升到「动作块」，用「最小证书内核 + 最小可行实验」验证其安全性与可用性。

## 0. 本轮增量模块

| 编号 | 名称 | 类型 | 关键作用（相对 HPC-E+ / v23） |
|---|---|---|---|
| IP-440 | ACCT (Action-Chunk Certificate Tube) | 块级证书 | 一次签发覆盖 H 步动作与整段状态管的证书，块内开环、块边界重规划 |
| IP-441 | MCK (Minimal Certificate Kernel) | MVP 内核 | 只保留 3 条不变式（几何 / 能量 / 义务），其余证书作为可选扩展，先跑通垂直切片 |
| IP-442 | COC (Chunk Obligation Carry-over) | 义务携带 | 把块内未到期义务压缩为残差义务，跨块归纳证明 |
| IP-443 | MVP-Prefix (Minimum Viable Prefix) | 执行策略 | 从已证块中取「够推进且可证」的最短前缀执行，兼顾响应性与摊销 |
| IP-444 | CBM (Chunk Boundary Monitor) | 运行时监控 | 块内检查点做廉价不变式检查，越管即中止并回退到 Exec_v23 |

### 0.1 「最小可行产品」的两种落地

1. **方法层 MCK**：不追求九证齐备，先固定三条不变式 `I1 几何无碰撞 ∧ I2 能量可行 ∧ I3 义务满足`；其余（专利、云边、少样本）作为**可插拔扩展**，在垂直切片跑通后再接入。
2. **实验层 MVE**：单机械臂 + 单相机 + 单禁入区 + 单能量预算，仪器化整条链路，优先暴露管误差与义务携带错误。

## 2. 形式模型

### 2.1 状态管传播

给定初始状态集 `R_t = {x_t}`（实测状态，或带测量噪声的球），对 τ = t,…,t+H−1：

```
R_{τ+1} = f(R_τ, a_τ) ⊕ B(w_max) ⊕ B(r_traj)
```

其中 `⊕` 为 Minkowski 和，`B(r)` 为半径 r 的球。工程上用 zonotope 实现，线性化误差单独计入 `r_traj`。

**关键选择**：把模型误差也折进 `r_traj`，而不是分开两套界，便于 conformal 直接给出概率保证。

### 2.2 能量上界

```
Ē_chunk = Σ_{τ=t}^{t+H−1} max_{x∈R_τ} e(x, a_τ) · Δt
```

要求 `Ē_chunk ≤ E_res`。若 `e` 对 x 是 L_e-Lipschitz，则可用 `e(x̂_τ,a_τ) + L_e·rad(R_τ)` 快速上界，避免在管上做优化。

### 2.3 义务与残差义务

义务 `O_j = (φ_j, d_j)`，语义：在 `[t, d_j)` 内所有状态必须满足 `φ_j`（例如禁入区外、护栏内）。块内检查：

```
OblSatisfied(O_j, R_tube, t, H) ≜ ∀τ ∈ [t, min(d_j, t+H)): ∀x∈R_τ: φ_j(x)
```

块末若 `d_j ≥ t+H`，则生成残差义务：

```
carry(O_j, H) = (φ_j, d_j − H)
```

若 `d_j < t+H` 则块内必须完成，否则该块不可签发。

### 2.4 块证书与谓词

```
C_chunk = (t, H, a_{t:t+H}, R_tube, Ē_chunk, O_carry, r_traj, V, sig, ip_tags)
```

```
TubeSound(R_tube, a, w_max, r_traj) ≜
    x_t ∈ R_t ∧ ∀τ: R_{τ+1} ⊇ f(R_τ,a_τ) ⊕ B(w_max) ⊕ B(r_traj)

ChunkSafe(C) ≜
    TubeSound(·)
  ∧ Ē_chunk ≤ E_res
  ∧ (∀O∈O_carry: OblSatisfied(O, R_tube, t, H))
  ∧ VersionConsistent(V)          # 复用 CESC.sync_predicate
  ∧ IPAttested(gen(C), tube(C))   # MVP 阶段仅两模块打标

ChunkExecutable(C) ≜ ChunkSafe(C) ∧ ∃ k∈[k_min,H]: ChunkSafe(prefix(C,k))
```

`Exec_v24 = Exec_v23 ∩ {π : ∃C, C 覆盖 π 且 ChunkExecutable(C)}`。

## 3. 算法骨架

```python
# ============================================================
# IP-440 / IP-441  ACCT + 最小证书内核
# ============================================================
@dataclass
class Obligation:
    pred: Callable[[Tensor], bool]   # φ_j
    deadline: float                  # 绝对时刻 d_j

@dataclass
class ChunkCertificate:
    t: float
    H: int
    actions: Tensor                  # [H, action_dim]
    tube: list[IntervalSet]          # R_t..R_{t+H}
    energy_ub: float
    carry: list[Obligation]
    r_traj: float
    version: VersionTuple
    sig: bytes
    ip_tags: tuple[str, ...]

class TubeBuilder:
    """zonotope 可达管；模型误差折入 r_traj。"""
    def __init__(self, f, w_max, r_traj, dt):
        self.f, self.w_max, self.r_traj, self.dt = f, w_max, r_traj, dt

    def build(self, x_t: Tensor, actions: Tensor) -> list[IntervalSet]:
        tube = [IntervalSet.point(x_t)]
        for a in actions:
            R_next = self.f(tube[-1], a) \
                     .minkowski(Ball(self.w_max)) \
                     .minkowski(Ball(self.r_traj))
            tube.append(R_next)
        return tube

class ACCTIssuer:
    def __init__(self, tube_builder, energy_fn, version_mgr, ipam,
                 alpha=0.01, k_min=2):
        self.tb = tube_builder
        self.e = energy_fn
        self.vm = version_mgr          # CESC
        self.ipam = ipam
        self.alpha = alpha
        self.k_min = k_min

    def issue(self, x_t, actions, obligations, E_res) -> ChunkCertificate | None:
        H = actions.shape[0]
        tube = self.tb.build(x_t, actions)

        # I2: 能量上界（Lipschitz 快速界）
        e_ub = 0.0
        for tau, a in enumerate(actions):
            e_ub += (self.e.nominal(tube[tau].center, a)
                     + self.e.lipschitz * tube[tau].radius) * self.tb.dt
        if e_ub > E_res:
            return None

        # I3: 义务块内检查 + 残差携带
        carry = []
        for ob in obligations:
            end = min(ob.deadline, x_t.time + H * self.tb.dt)
            if not all(ob.pred(x) for R in tube[:int((end - x_t.time)/self.tb.dt)+1]
                       for x in R.samples()):
                return None
            if ob.deadline >= x_t.time + H * self.tb.dt:
                carry.append(Obligation(ob.pred, ob.deadline - H * self.tb.dt))

        # 版本一致 + IP 打标
        if not self.vm.sync_predicate():
            return None
        if not self.ipam.verify_modules(["acct", "tube_builder"]):
            return None

        body = (x_t.time, H, actions, tube, e_ub, carry, self.tb.r_traj)
        return ChunkCertificate(*body, self.vm.current_version(),
                                sign(self.vm.sk, hash(body)),
                                ("IP-440", "IP-441", "IP-442"))

    def prefix(self, cert: ChunkCertificate, x_t, Phi, delta) -> int:
        """IP-443 最小可行前缀：最短的「推进达标且仍可证」前缀。"""
        for k in range(self.k_min, cert.H + 1):
            sub = self._restrict(cert, k)
            if not self._safe(sub):
                continue
            if Phi(sub.tube[-1].center) <= Phi(x_t) - delta * k * self.tb.dt:
                return k
        return cert.H if self._safe(cert) else -1

    def _restrict(self, cert, k):
        return replace(cert, H=k, actions=cert.actions[:k],
                       tube=cert.tube[:k+1])

    def _safe(self, cert):
        return (cert.energy_ub <= cert.version.E_res_ref
                and all(o.deadline > cert.t for o in cert.carry))
```

```python
# ============================================================
# IP-444 块边界 / 块内检查点监控（廉价、无阻塞 I/O）
# ============================================================
class ChunkBoundaryMonitor:
    def __init__(self, cert: ChunkCertificate, checkpoints=(1/3, 2/3)):
        self.cert = cert
        self.cps = {int(c * cert.H) for c in checkpoints}

    def check(self, tau_idx: int, x_meas: Tensor, energy_used: float) -> bool:
        # 1) 实测状态是否仍在证书管内（捕获管低估）
        if not self.cert.tube[tau_idx].contains(x_meas):
            return False
        # 2) 能量按比例预算（捕获能耗突增）
        frac = tau_idx / self.cert.H
        if energy_used > frac * self.cert.energy_ub * 1.1:
            return False
        # 3) 义务即时复核（廉价谓词）
        for ob in self.cert.carry:
            if not ob.pred(x_meas) and time.now() < ob.deadline:
                return False
        return True


# ============================================================
# 端到端：ACCT 接入 HPC-E+，失败即回退 Exec_v23
# ============================================================
class ChunkedPipeline:
    def __init__(self, hpc_e_plus, policy, issuer, Phi, delta=1e-3):
        self.hpc = hpc_e_plus
        self.policy = policy
        self.issuer = issuer
        self.Phi, self.delta = Phi, delta

    def step(self, obs, obligations, E_res):
        # 1) 策略一次输出整块
        actions = self.policy(obs.x, H=self.issuer.tb.H)

        # 2) 块级证书
        cert = self.issuer.issue(obs.x, actions, obligations, E_res)
        if cert is None:
            # 回退：单步逐步证书（Exec_v23），安全单调
            return self.hpc.admits_single_step(obs, E_res)

        # 3) 最小可行前缀（MVP）
        k = self.issuer.prefix(cert, obs.x, self.Phi, self.delta)
        if k < 0:
            return self.hpc.admits_single_step(obs, E_res)

        # 4) 开环执行 k 步，检查点监控
        mon = ChunkBoundaryMonitor(cert)
        spent = 0.0
        for i in range(k):
            x_next, e_i = self._apply(actions[i])
            spent += e_i
            if i in mon.cps and not mon.check(i, x_next, spent):
                return self.hpc.admits_single_step(obs, E_res - spent)
            obs.x = x_next
        # 5) 块末：残差义务交给下一轮
        return True, {"next_obligations": cert.carry, "prefix": k,
                      "version": cert.version, "energy_left": E_res - spent}
```

## 4. 正确性论证

### 引理 1（管可靠则整块安全）

**陈述**：若实际轨迹 `{x_τ}` 满足 `x_τ ∈ R_τ`（∀τ∈[t,t+H]），且 `ChunkSafe(C)`，则执行整块期间几何无碰撞、能量不超预算、义务不被违反。

**证明**：几何与义务谓词均在 `R_τ` 上全称量化，实际状态属于 `R_τ` 故继承成立；能量为 `R_τ` 上的上界，实际消耗 ≤ `Ē_chunk ≤ E_res`。∎

### 引理 2（轨迹级 conformal 覆盖）

**陈述**：令校准集轨迹非一致性分数 `S(ξ)=max_τ ‖x_τ−x̂_τ‖/σ_τ`，`q̂_α` 为其 (1−α) 分位数。若新轨迹与校准集可交换，则 `P(max_τ ‖x_τ−x̂_τ‖ ≤ q̂_α·σ_τ) ≥ 1−α`。

**证明**：split-conformal 对任意标量非一致性分数给出边际覆盖 `≥1−α`；此处分数取整条轨迹的最大值，故一次性覆盖**整块**，无需对 H 步做并集放大。∎

**推论**：取 `r_traj = q̂_α`，则引理 1 的「管可靠」以概率 `≥1−α` 成立，从而整块安全以 `≥1−α` 成立（其余为确定性界）。

### 引理 3（义务跨块归纳）

**陈述**：若初始义务集 `O_0` 成立，且对每个块 `i` 有 `OblSatisfied(O_carry^i)` 并按 `carry(·,H_i)` 生成 `O_carry^{i+1}`，则所有义务在其 deadline 前被满足。

**证明**：对块序号归纳。基例为初始义务。归纳步：块 i 覆盖 `[t_i, t_i+H_i)`；对 deadline `d_j`：若 `d_j < t_i+H_i`，由块内全称检查成立；否则残差义务把同一谓词与右移的 deadline 传入下一块，谓词在此期间持续被检查。deadline 严格递减 `d_j − ΣH`，故有限步后落入某块内被完成。∎

### 定理（摊销安全 + 单调退化）

**陈述**：在引理 1–3 下，`Exec_v24 ⊆ Exec_v23`，且块级方案的单步验证开销为 `c_tube + c_cert/H + c_mon`；当 `c_cert ≫ c_tube` 且 H 增大时，相对逐步证书的摊销比趋于 `H`。

**证明**：
1. 包含关系：`Exec_v24` 是 `Exec_v23` 与块谓词的交集，且任何失败分支都显式回退 `admits_single_step`，故不会引入 `Exec_v23` 之外的计划。
2. 开销：管传播每步 `c_tube`，签名/版本/IP 检查每块一次 `c_cert`，检查点每块常数次 `c_mon`，合计除以 H 得每步开销。
3. 前缀缩短只会减少覆盖范围、不增加新状态，故 `ChunkSafe(prefix)` ⇒ 执行前缀安全。∎

### 命题（最小可行前缀不破坏安全，但影响摊销）

**陈述**：执行 `k* < H` 的前缀仍满足引理 1，但有效摊销比从 `H` 降为 `k*`；若 `k*` 频繁贴近 `k_min`，块级优势消失。

**证明**：前缀是原块的子集，管与上界均被截断，安全继承；开销按 `k*` 重算即得。∎

**实践含义**：`δ` 与 `k_min` 是「响应性 ↔ 摊销」的旋钮，必须联合调参，不能各自最优。

## 5. 复杂度

| 模块 | 时间复杂度 | 空间 | 关键参数 |
|---|---|---|---|
| 管传播（zonotope） | O(H·n·g)（n 维数，g 生成元数） | O(H·g) | H≤20, n≤7, g≤32 |
| 能量上界 | O(H·n) | O(1) | Lipschitz 界 |
| 义务检查 | O(H·|O|·s) | O(|O|) | s 采样点数 |
| 最小可行前缀 | O(H²)（可增量降为 O(H)） | O(H) | 复用已算管 |
| 块内监控 | O(1)/检查点 | O(1) | 2 个检查点 |
| 每步摊销 | `c_tube + c_cert/H + c_mon` | — | 目标 <20ms @50Hz |

## 6. 实验设计（MVE）

### 6.1 MVE-1：块级 vs 逐步证书

2D 平面机械臂 + 单禁入区 + 能量预算；同一策略输出 H 步。

| 指标 | 逐步证书 (v23) | ACCT H=5 | H=10 | H=20 | 目标 |
|---|---|---|---|---|---|
| 验证 CPU (ms/步, P99) | 基线 | ↓ | ↓↓ | ↓↓↓ | <20ms 不退化 |
| 碰撞率 (/千步) | 基线 | ≤基线 | ≤基线 | ≤基线 | 0 硬碰撞 |
| 能量越界率 | 基线 | ≤基线 | ≤基线 | ≤基线 | 0 |
| 义务违反率 | 基线 | ≤基线 | ≤基线 | ≤基线 | 0 |
| 任务成功率 | 基线 | ≥ | ≥ | ?（保守度） | ≥基线 |
| 重规划次数 | 每步 | 1/H | 1/H | 1/H | 摊销可见 |
| 管体积 / 可行块比例 | — | — | — | — | 记录可用性拐点 |

### 6.2 MVE-2：消融

| 变体 | 目的 | 预期 |
|---|---|---|
| 去掉 COC（义务携带） | 证明边界是主风险 | 跨块 deadline 违反显著上升 |
| 去掉 CBM（边界监控） | 量化管低估的代价 | 注入模型误差后出现「假安全」 |
| 固定区间替代 conformal 管 | 对比保守度与保证 | 覆盖失效但可用性上升（反面教材） |
| 前缀恒取 H（无 MVP） | 隔离前缀策略影响 | 摊销最好但响应最差 |

### 6.3 MVE-3：块内分布突变

在块中点注入负载变化 / 摩擦突变 / 光照突变。测：检测延迟（步）、回退率、回退后是否仍安全。目标：检测延迟 ≤ 1 个检查点（≈H/3 步），回退率 <5%。

## 7. 风险与缓解

| 编号 | 描述 | 严重度 | 缓解 | 剩余风险 |
|---|---|---|---|---|
| R1 | 管低估（接触/未建模动力学）导致「假安全」 | 最高 | 块内检查点 CBM；conformal 管半径；越管立即中止并回退 | 突变发生在检查点之间仍可能漏检 |
| R2 | 管过保守 → 长块无可行解，可用性崩塌 | 高 | 自适应 H；数据驱动管半径；MVP 前缀缩短 | 接触丰富任务可能退化为 H=1 |
| R3 | 义务跨块携带错误导致 deadline 漏检 | 高 | 引理 3 的归纳不变式 + 单元测试；块末强制复核 | 激活型义务（块内新触发）需额外机制 |
| R4 | 最小可行前缀频繁贴近 k_min → 摊销失效 | 中 | 联合调 δ/k_min；滞后阈值防抖 | 高动态任务天然需要短前缀 |
| R5 | 轨迹级 conformal 在分布漂移下失效 | 中 | 复用 FSVC 覆盖率监控；跌破即回退单步 | 交换性假设无法在线验证 |

## 8. 本轮最大风险（一句话）

**一句话**：块级证书的全部安全性都押在「状态管确实包住真实轨迹」上——一旦接触或未建模动力学让管被低估，ACCT 就会把一个危险的中间动作打包进一张看似安全的块证书里，此时「最小可行产品」反而成了「最小可行事故」。
