# 第 2 轮迭代（灵感循环：「成功率」×「开源生态」）—— 成功率优先，把开源生态蒸馏成一只单模型

> **承接 v2（UIP-01′~15），但换目标函数。** v2 的旗舰 RHPV-D 优化的是"失败时尽量保住步骤分"：检测进度被撤回→重做。这个机制本身没错，但它隐含了一个未经检验的权重假设——步骤分很值钱。榜单的第一口径其实是**平均成功率**；而成功率是**乘性**的（任何一步失败，整条任务失败）、**有暴露窗口**的（跑得越久，越容易被人为干扰撤回）、**小样本高噪声**的（n=10、p=0.3 的 95% 区间宽达 49.5 个百分点）。本轮两个灵感词正好把这三点逼出来：
> - **「成功率」**：不是赛后看的百分数，而是一个可以被分解、被分配、被置信区间约束的**优化对象**。
> - **「开源生态」**：不是"借一个更强的模型"，而是一个**教师动物园**——OpenVLA / π0 / GR00T / RDT / SmolVLA / Unitree WLA 等教师的错误互不相同；但比赛要求单模型，所以真正的技术是**把教师动物园蒸馏成一只学生**，而不是推理期集成。
>
> **一句话：从"步骤分安全网"转向"成功率优先的开源生态蒸馏"；恢复不再默认正确，而是一笔要在 deadline、暴露风险和验证器精度下算账的投资。**

---

## 0. 先给直觉：四个反例

1. **"修最差的任务"不一定最划算。** 成功率是乘性的：`SR_t = ∏ q_i`。修第 i 步的边际收益是 `∂SR_t/∂q_i = ∏_{j≠i} q_j = SR_t/q_i`。所以最值得修的不是"最差的步"，而是"**其余步都稳、只有这一处弱**"的步。一个处处都弱的任务，SR 已经接近 0，修一步的绝对增量反而很小。
2. **同样的单步改进，短任务的成功率增量更大。** 2 步任务每步 0.8 → SR=0.64；5 步任务每步 0.8 → SR=0.33。把某一步从 0.8 提到 0.9，2 步任务的 ΔSR≈0.08，5 步任务只有≈0.041。32 个任务里 11 个是 2 步、14 个是 3 步——**成功率口径下，任务长度本身就是一种"杠杆"**，不能只按难度排序。
3. **成功率是"数出来的比例"。** 若每任务只跑 n=10 次，真实 p=0.30 的 95% Wilson 区间是 [10.8%, 60.3%]。离线 A/B 若不做配对、序贯或置信下界，就会把噪声当进步；排行榜上 <5pp 的差距，在几十个 episode 下基本不可辨识。
4. **开源生态不是"更强的单体"，而是"更分散的错误"。** 一个教师均值 55%，另一个教师均值 52%，但两者错误高度相关时，蒸馏后的学生不会比最好的单教师强多少；反之，错误不相关的教师组合，即使单体更弱，oracle 路由上界也可能高出一大截。**多样性是资产，集成是负债（合规），蒸馏是变现方式。**

## 1. 上一版的诊断：三个需要修正的偏置

- **偏置 A：把"步骤分"当成主目标。** v2 的 UIP-02′/09′/15 都在优化"失败时保住步骤分"。如果榜单是成功率优先（或成功率权重更高），这些机制的边际价值被系统性高估；更糟的是，为了多保一步而多花的时间，会通过暴露窗口**反过来降低成功率**。
- **偏置 B：把"恢复"当成默认正确。** 恢复有三个成本：① 消耗 episode 时间，可能挤掉后续步骤；② 增加墙钟时间，增加被人为干扰再次撤回的暴露；③ 验证器的假阳性会触发不必要的重做。**恢复的净收益 = 成功率增益 − 时间成本 − 暴露成本 − 假阳性成本**；在 deadline 紧时，首次成功率与速度可能比恢复更重要。
- **偏置 C：把 Gazebo 当"成功率神谕"。** 仿真给的是 `p_sim`，不是 `p_real`。GSO 应该降级为**教师/负样本工厂 + 结构/顺序裁判**，不能当成功率裁判；它的偏差会随任务和扰动类型变化，不能直接外推榜单。
- **保留但重定位：** UIP-11（GSO）→ 教师/负样本工厂；UIP-12（DRF）→ 扰动恢复数据源；UIP-14（MSGR）→ 学生架构的技能头；UIP-13/08′（ACS/LAT-ENG）→ 成功率模型里的"暴露时间"旋钮；UIP-01′（RHPV-D）→ 受预算和置信度约束的运行时恢复；UIP-15（CSG）→ 假阳性/延迟护栏。

## 2. 两个灵感词的严谨解读

### 2.1 「成功率」：乘性过程 × 暴露过程 × 估计过程

**直觉。** 官方只给一个百分数，但那个百分数背后至少有三层：任务内（K 个计分步的条件成功率相乘）、时间上（干扰按时间到达，越慢越容易被撤回）、统计上（n 个 episode 的二项抽样）。把三层拆开，才知道该修哪一步、该不该加速、实验要跑多少次。

**定义 1（乘性成功模型）。** 设任务 t 有 K_t 个有序计分步，权重 `w_{t,i}`，`Σ_i w_{t,i}=100`。令 `q_{t,i}` 为"前 i−1 步已完成时，第 i 步在预算内最终完成"的概率。则

```text
SR_t   = ∏_{i=1..K_t} q_{t,i}                     # 任务成功率
SS_t   = Σ_{i=1..K_t} w_{t,i} · ∏_{j≤i} q_{t,j}   # 期望步骤分
ΔSR_t  = (SR_t / q_{t,i}) · Δq_{t,i}              # 单步改进的绝对增益
```

**定义 2（暴露模型）。** 设任务墙钟时间为 `T_t`，人为撤回的到达率为 `μ_t`，单次撤回被恢复的概率为 `r_t`。则

```text
SR_t ≈ (∏_i q_{t,i}) · exp( −μ_t (1−r_t) T_t )
```

恢复率 `r_t` 既降低有效风险，又抬高 `T_t`；**恢复是否值得，取决于它把 `(1−r)T` 压低得比 `T` 增长得更快**。这把"实时性"第一次变成成功率的自变量，而不只是可信度指标。

**定义 3（估计模型）。** n 次试验的成功次数 `X ~ Binomial(n, SR_t)`。用 Wilson 区间报告不确定性；A/B 的样本量由下式给出（非配对）：

```text
n ≈ (z_{1−α/2} + z_{1−β})² · [p₁(1−p₁) + p₂(1−p₂)] / Δ²
```

配对设计（同一初始状态/随机种子）把括号替换为 `p₁(1−p₁)+p₂(1−p₂)−2ρ√(p₁(1−p₁)p₂(1−p₂))`。**推论：小样本只能分辨大效应；<5pp 的领先在统计上通常是幻觉。**

**定义 4（成功率—步骤分交换率）。** 若榜单效用是 `U = λ·SR + (1−λ)·SS/100`，则无差异交换率为

```text
dSS/dSR = −100λ/(1−λ)          # SR 以 0–1 计
⇒ 每 1 个百分点成功率，值 λ/(1−λ) 个步骤分
```

λ=0.5 时 1pp SR ≈ 1 个步骤分；λ=0.7 时 ≈2.33；λ=0.9 时 ≈9。若榜单是字典序（成功率优先），交换率是无穷大。**在不知道 λ 的情况下，正确做法不是猜一个权重，而是输出 (SR, SS) 的 Pareto 前沿，并只在"用最多 1.32pp 步骤分换 1pp 成功率"的经验前沿以内做交易**（工作区 fixture 的跨模型拟合约为 `step ≈ 0.51 + 1.321·success`；这是相关关系，不是因果交换率，只能当 sanity check）。

### 2.2 「开源生态」：教师动物园 × 数据/工具生态 × 合规供应链

**直觉。** 开源生态提供三样东西：① **教师**（预训练 VLA/机器人基础模型），② **数据**（HF 上的 32 任务、Open X-Embodiment、DROID、RoboMIND 等），③ **工具链**（LeRobot、Isaac Lab、MuJoCo、Gazebo、ROS 2）。但比赛要的是**一个**模型、**一个** `get_action`，所以不能把"集成"直接搬上评测端。开源生态的真正价值是：**用教师的错误多样性，去教一个学生；用教师的数据覆盖，去补学生的盲区；用开源工具，把这条流水线做得可复现。**

**定义 5（教师动物园的生态溢价）。** 设教师 `m=1..M` 在任务 t 上的成功率为 `p_{m,t}`。则

```text
best_single  = max_m  (1/32) Σ_t p_{m,t}
oracle_route = (1/32) Σ_t max_m p_{m,t}
ecosystem_premium = oracle_route − best_single
```

`oracle_route` 是"如果能在每个任务上选对教师"的上界；`best_single` 是"只选一个全局最强教师"的下界。**生态溢价的大小，取决于教师之间的错误相关性，而不是它们各自的均值。** 蒸馏学生若任务识别/路由准确率为 `1−ε`、模仿误差为 `δ`，则其上界约为

```text
SR_student ≤ (1−ε)·oracle_route + ε·average_teacher − δ
```

所以"教师越多越好"是错的：**ε（路由错误）和 δ（蒸馏差距）会吃掉溢价**。真正要优化的是"在给定学生容量下，选一组**错误最不相关**的教师"。

**定义 6（生态的三层供应链）。**

| 层 | 提供什么 | 你要付出什么 | 主要风险 |
|---|---|---|---|
| 教师 | 预训练权重、技能先验、动作空间 | 推理/蒸馏算力；接口对齐 | 许可不兼容、预训练污染、版本漂移 |
| 数据 | 32 任务演示、跨 embodiment 数据、仿真数据 | 清洗、重定向、配比 | 许可、embodiment 不匹配、测试集污染 |
| 工具 | LeRobot/Isaac/Gazebo/ROS 2 等 | 工程集成、复现 | 依赖锁定、仿真—真机差距 |

**合规是硬约束。** 单模型多任务、只允许 `observation→action`、外部 API 可能被判违规；因此：**推理期只部署一个 checkpoint、一次前向（或一个模型的多技能头），集成只发生在训练/蒸馏期**。许可证、污染、版本、安全（safetensors、无 pickle）都要进审计表，而不是脚注。

## 3. 瓶颈假设（更新）

- **H1（目标偏置）**：在成功率口径下，真正的瓶颈是"到达最后一步的乘性概率"，不是"最后一步的精度"；短任务、高 reach 任务被 v2 低估。
- **H2（生态溢价）**：开源教师的价值主要来自**错误多样性**；oracle 路由上界显著高于 best single，但蒸馏差距和路由误差会吃掉大部分溢价。
- **H3（恢复的净收益）**：恢复的收益是 `ΔSR_recover`，成本是 `ΔT`（挤占后续步骤）、`μ(1−r)ΔT`（暴露）和假阳性重做；在 deadline 紧、验证器精度低时，恢复可能降低成功率。
- **H4（估计噪声）**：<5pp 的榜单差异在几十个 episode 下不可辨识；必须用配对/序贯/置信下界，实验要先算样本量再跑。
- **H5（合规）**：许可、单模型、测试污染是硬约束；一个不合规的 +5pp 可能直接归零。

## 4. 候选与合并 → v3 清单

围绕两词发散 10 个草案，合并后得到 v3 清单：**旗舰 UIP-16（SR-D2，成功率感知的蒸馏-多样化）**，支撑 UIP-17（成功率组合配置）、UIP-18（LCB/CVaR 选择门）、UIP-19（开源合规/来源门）、UIP-20（末步转化）、UIP-21（公开评测复刻，可选）；v2 的 01′/02′/08′/11/12/13/14/15 保留但重定位，05 保留，04/10 继续封存。详见产物区。

**为什么旗舰从"恢复"换成"蒸馏"？** 因为恢复只能救"已经发生的失败"，而蒸馏改变的是"失败发生的概率"——前者是局部补丁，后者是成功率的主项。恢复仍然保留，但它降级为 UIP-16 学生身上的一个**受预算约束的运行时子程序**，而不是全轮叙事的中心。

## 5. 本轮最大风险

**一句话：最大的风险是把"教师动物园的 oracle 上界"误当成"单模型学生的真实成功率"——许可、污染、路由误差和蒸馏差距中的任何一项，都可能把离线 +10pp 变成线上负迁移或直接取消资格；因此 UIP-19 的合规/来源门必须与 UIP-16 同时上线，且所有收益先按蒸馏差距打折、再用配对真机评测兑现。**

**→ 本轮最值得押注：UIP-16（SR-D2）× UIP-19（OSS-Gate）组成的"合规蒸馏闭环"——它把开源生态的多样性变成单模型可部署的成功率，同时把最大的合规/污染风险前置成硬门；再用 UIP-18 的置信下界和 UIP-20 的末步转化决定把算力花在哪。**

## 1. 旗舰深潜：UIP-16 · SR-D2（Success-Rate-aware Distill-and-Diversify）

### 1.1 机制（直觉先行）

**直觉。** 开源生态里有多种教师，它们的强项不同：有的擅长抓取/放置，有的擅长细接触（插、拧、拉拉链），有的视觉泛化好但动作粗糙。**最优的部署不是一个全局最强的教师，而是"在每个任务上选对该任务的专家"**。但比赛只允许一个模型，所以把这个"路由器"蒸馏进一个学生：学生看 `language + 首帧/历史`，既输出动作，也输出"当前该学哪个教师的风格/技能头"的隐变量。训练期可以集成、可以多教师伪标签；推理期只有一个 checkpoint。

**严谨表述。** 给定教师集合 `T={π_1..π_M}`、32 任务分布 `P_task`、学生容量 `C`，目标是

```text
θ* = argmin_θ  E_{t~P_task, o~D_t} [ L_action(π_θ(o), a*) 
                                   + λ1 · L_success(σ(f_θ(o)), 1[episode succeeds])
                                   + λ2 · KL( π_θ(·|o) || Σ_m α_m(o) π_m(·|o) ) ]
s.t.  θ 是单一 checkpoint；α_m(o) 是教师路由权重（仅训练期可用）
```

- `L_action`：在 32 任务 + DRF 扰动数据上的行为克隆/流匹配损失。
- `L_success`：**成功率感知**的辅助头。学生必须预测"当前子目标在未来 k 步内完成的概率"，用校准后的 `q̂` 驱动运行时的推进/重试/止损。这是与普通行为克隆的关键区别：**只模仿成功动作，会学到"看起来像成功"的动作，而不会学到"什么时候该停/该重做"**。
- `KL` 项：把教师动物园的"软路由"蒸进学生；`α_m(o)` 在训练期由任务标签、语言、首帧和教师一致性共同决定；推理期不需要教师。

### 1.2 与 v2 的差异

- v2 的 UIP-14 是"单骨干 + 技能头"的模块化；SR-D2 把"技能头"升级为"**教师专家的蒸馏目标**"——技能头不再手工定义，而由教师动物园的强项自动发现。
- v2 的 UIP-12 只造"扰动-恢复"数据；SR-D2 还把教师在这些数据上的**成功/失败伪标签**当作额外监督，用来训练 `L_success`。
- v2 的 UIP-01′ 是推理期验证器；SR-D2 把验证器的"成功概率"变成学生自己的输出头，减少对外部 VLM/规则的依赖，规避"非单模型"合规风险。

### 1.3 教师选择：多样性优先，不是均值优先

**直觉。** 选 5 个都是 55% 且错误高度相关的教师，不如选 1 个 55% + 4 个 50% 但错误模式互补的教师。因为蒸馏的目标不是"复制一个教师"，而是"覆盖教师们的联合知识"。

**可操作准则（子模贪心）。** 对候选教师子集 `S`，定义覆盖分数

```text
F(S) = (1/32) Σ_t max_{m∈S} p_{m,t}  −  γ · Cost(S)  −  η · LicenseRisk(S)
```

`max` 覆盖是单调子模的，因此贪心 `S ← S ∪ {argmax_m F(S∪{m})}` 有 `(1−1/e)` 近似保证（在无成本项时）。实际中再加两个约束：

1. **错误相关性惩罚**：`F(S) − β·mean_{m≠m'} corr(err_m, err_m')`，避免选到"同源微调"的伪多样教师。
2. **蒸馏可行性惩罚**：教师之间的动作空间/观测约定必须能对齐到同一个 canonical schema，否则 `δ`（蒸馏差距）会吞掉溢价。

### 1.4 伪代码

```python
# UIP-16: 训练期（可集成、可多教师）；推理期只有一个 student
class SRD2_Trainer:
    def __init__(self, teachers, student, task_data, drf_data, oss_gate):
        self.teachers = oss_gate.filter(teachers)      # UIP-19: 许可/污染/版本/安全
        self.student  = student                        # 单 checkpoint
        self.task_data = task_data                     # 32 任务 + 5 泛化轴
        self.drf_data  = drf_data                      # UIP-12 扰动-恢复

    def select_teachers(self, B=8, gamma=0.1, beta=0.5):
        S = []
        while len(S) < B:
            m = argmax_{m not in S} coverage(S+[m]) - gamma*cost(m) - beta*corr(S,m)
            S.append(m)
        return S

    def fit(self, S, steps):
        for step in range(steps):
            batch = sample_mixture(self.task_data, self.drf_data)
            # 1) 教师软标签（仅训练期）
            with torch.no_grad():
                teacher_actions = [pi(batch.obs) for pi in S]
                alpha = route_weights(batch.language, batch.first_frame, teacher_actions)
            # 2) 学生动作损失 + 成功率辅助头 + 蒸馏 KL
            a_pred, q_pred = self.student(batch.obs)
            L = action_loss(a_pred, batch.action)
            L += lambda1 * success_loss(q_pred, batch.success_label)   # 校准
            L += lambda2 * distill_kl(self.student.logits, teacher_actions, alpha)
            L += lambda3 * calibration_loss(q_pred, batch.success_label)  # ECE/Brier
            update(self.student, L)

    def export(self):
        # 只导出 student；不导出任何教师/路由/ensemble
        return self.student.state_dict()
```

```python
# UIP-16 + UIP-01′ + UIP-18: 推理期，单模型、预算感知
class SRD2_Policy:
    def __init__(self, student, K_MAX=8, conf_thr=0.6,
                 max_redo=2, latency_budget_ms=200, deadline_ms=None):
        self.student = student
        self.K_MAX = K_MAX
        self.conf_thr = conf_thr
        self.max_redo = max_redo
        self.latency_budget_ms = latency_budget_ms
        self.deadline_ms = deadline_ms
        self.reset()

    def reset(self):
        self.g = 0            # 当前计分步索引
        self.redo = 0
        self.buf = []
        self.t_used_ms = 0

    def get_action(self, obs):
        # 1) 用学生自己的成功头做进度核验（无需外部 VLM）
        q_done, q_reg = self.student.progress_head(obs, self.g)
        if q_reg > self.conf_thr and self.redo < self.max_redo:
            if self._budget_allows_redo():
                self.redo += 1
                self.buf = []          # 重做当前子目标
        elif q_done > self.conf_thr:
            self.g += 1
            self.redo = 0

        # 2) 预算感知：deadline 紧时优先推进，不无限重做
        if not self.buf:
            k = self._pick_k(obs)      # UIP-13: 接触密集步用小 k
            self.buf = list(self.student.get_action(obs, k))[:k]
        return self.buf.pop(0)

    def _budget_allows_redo(self):
        if self.deadline_ms is None:
            return True
        # 粗估：一次重做至少需要一个块的时间；留出剩余步骤的预算
        remaining_steps = self.student.K_remaining(self.g)
        return self.t_used_ms + self.latency_budget_ms * (self.redo + remaining_steps) < self.deadline_ms
```

### 1.5 可行性、资源、落地

- **可行性：中高。** 教师都是现成开源权重；难的是**接口对齐**（动作空间、夹爪约定、观测键）和**许可/污染审计**，不是训练算法本身。
- **资源：** 1 张训练卡做 LoRA/适配器蒸馏；32 任务数据 + DF 数据；教师推理可离线批处理，不必在评测端跑。
- **落地步骤：**
  1. 建 canonical schema（`left/right_arm[7]`、`left/right_gripper[1]`、`pivot[7]`、4 路图、`language`），把每个教师的输出映射进来；
  2. 用 UIP-19 过滤教师，用 UIP-18 在本地复刻评测上排教师；
  3. 用 UIP-17 选教师子集与数据配比；
  4. 蒸学生（动作 + 成功率头 + 校准）；
  5. 用 UIP-20 做末步专攻，用 UIP-01′/15 做预算内恢复；
  6. 配对真机评测，按 UIP-18 的 LCB 决定是否上线。
- **风险：** 蒸馏差距、路由错误、许可/污染；用 UIP-19 前置，用 UIP-18 的置信下界做上线门。

## 2. UIP-17 · SR-Portfolio（成功率组合配置）

**直觉。** 训练预算不是"平均分给 32 个任务"，而是一个**受约束的投资组合**：每个任务/泛化轴/教师/扰动增强都是一项资产，有成本、有期望成功率增益、有方差、还有彼此之间的正/负迁移。目标不是最大化单任务，而是最大化**稳健的宏平均成功率**。

**定义。** 设干预 `j` 的成本 `c_j`、期望增益 `ΔSR_j`、方差 `σ_j²`，预算 `B`。配置问题：

```text
max_x   E[SR(x)] − β·Var[SR(x)]        # 或 max CVaR_α(SR(x))
s.t.    Σ_j c_j x_j ≤ B,  x_j ∈ {0,1}
```

由于乘性成功模型在 `q` 上非凹（边际增益 `SR/q` 随 `q` 上升而上升），裸贪心会**过度集中**。工作区玩具模拟已经显示：按原始导数贪心分配 32 个单位，宏平均 SR 只有 27.1%，反而低于"每任务各升一步"的 31.6%——这就是"myopic greedy 在非凹目标上翻车"的示例。正确做法：

1. 用**有限视界边际增益**（一次只升 5pp，升到 0.95 封顶）而不是连续导数；
2. 加**负迁移惩罚**：用 leave-one-task-out 估计 `T_{t,t'}=∂SR_t/∂(对 t' 的投资)`，只投正迁移；
3. 用**贝叶斯 bandit / 序贯实验**更新 `ΔSR_j` 的后验，而不是一次性拍脑袋；
4. 优先"高 reach + 一个弱步"和"高 reach + 低末步"的干预（见 UIP-20）。

**关键定性结论（待真机验证）：** 成功率口径下，任务长度是杠杆：2 步任务对单步改进最敏感；"救最差任务"与"最大化边际成功率"在玩具模型里几乎反相关。真机实验必须检验这个反直觉结论，而不是直接照搬。

## 3. UIP-18 · LCB-Gate（置信下界/尾部风险选择门）

**直觉。** 榜单是一个**带噪声的估计**。用均值选 checkpoint，会选到"运气好"的那个；用置信下界选，才会选到"更可能真的更好"的那个。成功率的分布还是重尾的：一个任务 0%、另一个 80%，均值和最差任务的表现可能完全不同。

**定义。**

```text
LCB_t = Wilson_lower( X_t, n_t, α )          # 单任务成功率下界
LCB_macro = (1/32) Σ_t LCB_t                  # 保守宏平均
CVaR_α = E[ SR | SR ≤ Quantile_α(SR) ]        # 尾部风险（按任务/按 episode）
θ* = argmax_θ [ LCB_macro(θ) ]  或  argmax_θ [ CVaR_α(θ) ]
```

**样本量先算再跑。** 用 §7 的公式：检测 30%→35% 的 5pp 提升，80% power 下非配对约需 **1083** 个 episode/策略；配对且 `ρ=0.5` 约 **542**；`ρ=0.8` 约 **218**。这直接决定实验设计：**要么做配对/分层，要么只追 >10pp 的大效应**，不要在 3pp 的噪声里做 20 组消融。

**早停规则。** 当 `LCB(Δ) ≤ 0` 连续 N 次评估时停止该分支；避免把算力烧在统计上不可辨识的改进上。

## 4. UIP-19 · OSS-Gate（开源合规/来源门）

**直觉。** 开源生态是双刃剑：它给你免费的能力，也给你免费的许可证风险、污染风险和供应链风险。比赛是单模型、远程 API、可能还有"不得使用外部服务"的规则；一个不合规的 +10pp 可能直接归零。

**五道硬门（全部通过才允许进入 UIP-16）：**

| 门 | 检查 | 失败后果 | 处置 |
|---|---|---|---|
| L 许可 | 代码/权重/数据的许可证是否允许比赛使用与再分发；衍生权重是否继承限制 | 取消资格/法律风险 | 只保留 Apache-2.0/MIT/BSD 等 permissive；非商用/研究-only 的一律不用 |
| C 污染 | 教师预训练数据是否包含挑战任务/测试集/同源数据 | 离线虚高、线上崩 | 做 contamination probe：对比 seen/unseen 物体与背景；异常则降权或排除 |
| V 版本 | commit/权重 hash/环境是否可复现 | 结果不可复现 | 锁 hash、锁依赖、写 manifest |
| S 单模型 | 推理期是否只有一个 checkpoint、一次前向/一个模型的多头 | 违反"单模型" | 集成/路由只放训练期；导出前做"单模型审计" |
| Sec 安全 | 权重格式、反序列化、依赖供应链 | 任意代码执行 | 只用 safetensors；不加载 pickle；扫描依赖 |

**可复现 manifest（最小字段）：** 任务数据版本、教师列表+hash、学生配置、随机种子、硬件、评测脚本 commit、每个实验的 episode 数与 Wilson 区间。

## 5. UIP-20 · F2S（Final-to-Success，末步转化）

**直觉。** 成功率是 0/1；步骤分是连续的。一个 episode 如果已经完成了前 K−1 步，只差最后一步，那么把它从 0 变 1 的边际价值是**整条任务的成功率**，而不是最后一步的权重。**"末步转化"是成功率口径下最便宜的杠杆之一。**

**定义。** 令 reach `R_{t,K−1}=∏_{i<K} q_{t,i}`，末步成功率 `q_{t,K}`。则

```text
SR_t = R_{t,K−1} · q_{t,K}
∂SR_t/∂q_{t,K} = R_{t,K−1}
```

优先级 = `R_{t,K−1} × (可提升的 q 空间) / 成本`。高 reach、低末步的任务最值得投；低 reach 的任务应先修前面的瓶颈，而不是死磕末步。

**落地。** 在 SR-D2 里加一个**末步专家头**：用教师中"细接触/插入/合拢"强的子集专门蒸这个头；运行时用 UIP-01′ 的成功头检测"是否已到末步"，若是，则切到更小 `k`、更高验证频率、更保守的重试预算。

## 6. UIP-21 · Eval-Replica（公开评测复刻，可选）

**直觉。** 官方榜单还没上线，最大的信息缺口是"我到底在真实协议下能得多少分"。用官方 `unibot_submission` 的接口和 `metadata` 约定，在本地复刻一个**同形状**的评测器：同样的 `get_action` 循环、同样的块长语义、同样的 N 端口隔离、同样的 episode 预算。它不是官方评测，但能把"接口错误/形状错误/状态泄漏"这类致命问题在提交前暴露出来。

## 7. 关键推导

### 7.1 乘性成功率的边际增益

```
SR_t = ∏_{i=1..K} q_i
∂SR_t/∂q_i = ∏_{j≠i} q_j = SR_t / q_i
```

**读法：** 修一个"其余步都稳"的弱步，比修一个"处处都弱"的任务里的同一步更值；短任务（K 小）对单步改进更敏感。

### 7.2 成功率—步骤分交换率

```
U = λ·SR + (1−λ)·SS/100
dU = λ dSR + (1−λ)/100 dSS
dSS/dSR = −100λ/(1−λ)          # 以"SR 的 1.0（100pp）"为单位
⇒ 每 1pp SR 值 λ/(1−λ) 个步骤分
```

λ=0.5 → 1pp SR ≈ 1 分；λ=0.7 → ≈2.33 分；λ=0.9 → ≈9 分；字典序 → ∞。**在 λ 未知时，输出 Pareto 前沿，不猜单点。**

### 7.3 暴露时间与恢复

```
SR ≈ (∏ q_i) · exp(−μ(1−r)T)
∂ln SR/∂T = −μ(1−r)
```

恢复率 `r` 提高会降低有效风险，但重做会增大 `T`。**净收益符号 = Δ[−μ(1−r)T] − 时间机会成本 − 假阳性成本。**

### 7.4 样本量与可辨识性

```
n_unpaired ≈ (z_{1−α/2}+z_{1−β})² [p₁(1−p₁)+p₂(1−p₂)] / Δ²
n_paired   ≈ 同式，括号减去 2ρ√(p₁(1−p₁)p₂(1−p₂))
```

5pp、30%→35%、80% power：非配对 ≈1083；ρ=0.5 ≈542；ρ=0.8 ≈218。

### 7.5 生态溢价与蒸馏上界

```
best_single  = max_m (1/32) Σ_t p_{m,t}
oracle_route = (1/32) Σ_t max_m p_{m,t}
premium      = oracle_route − best_single
SR_student  ≤ (1−ε)·oracle_route + ε·average_teacher − δ
```

**读法：** 教师越多不等于越好；`ε`（路由错误）和 `δ`（蒸馏差距）是溢价的漏损项。选教师时要同时优化覆盖、错误相关性和可蒸馏性。

| 8 个教师的 oracle 覆盖 | 70.4% |
| 学生（ε=0.1 路由错误） | 67.3% |

**观察：** 即使有 10% 路由错误，蒸馏学生（67.3%）仍高于 best single（55.0%）；但若 `ε→0.5`，学生掉到 52.3%，低于 best single。**路由准确率是生态溢价的命门。**

### 8.6 假阳性验证器下的恢复（3 步任务，deadline=1.2s，真撤回率 μ）

| 假阳性 ε | μ=0：不重做 / 总重做 / 预算感知 | μ=0.15：不重做 / 总重做 / 预算感知 |
|---|---|---|
| 0.00 | 55.0 / 55.1 / 84.9 | 54.0 / 53.9 / 81.2 |
| 0.10 | 55.2 / 52.7 / 75.4 | 54.0 / 50.9 / 71.7 |
| 0.20 | 55.1 / 49.7 / 66.2 | 54.0 / 47.6 / 62.7 |

**观察：** ① 预算感知重做显著优于"不重做"和"无脑重做"；② 假阳性从 0→0.2 时，"无脑重做"从 55.1% 掉到 49.7%（低于不重做的 55.1%），而预算感知从 84.9% 掉到 66.2%，仍明显高于不重做。结论：**恢复要有预算门 + 验证器置信门；假阳性会吃掉恢复收益，但在同样的假阳性下，预算感知仍是最稳的。**

## 9. 实验设计 E201–E212

|---|---|---|---|
| E201 | 乘性模型 vs 加性模型 | 预测 SR 的校准/R² | 乘性模型显著更好；否则重估 q |

## 10. 合规与风险清单

- **许可：** 教师/数据/代码逐项登记；非商用/研究-only/自定义许可一律排除；衍生权重也要查。
- **污染：** 教师预训练是否含挑战任务/测试集；做 seen/unseen 探测；污染教师降权或排除。
- **单模型：** 推理期一个 checkpoint、一次前向（或一个模型的多头）；集成/路由只在训练期；导出前跑"单模型审计"脚本。
- **接口红线：** 形状/dtype/token/块长严格按 `unibot_submission` README；返回块长与声明不一致、动作统计异常都会伤可信度。
- **仿真过拟合：** GSO/DRF 只做结构/顺序/负样本；所有真机结论提测前标注"代理"，并用配对真机锚点校准。
- **统计过拟合：** 小样本榜单差异不当真；用 LCB/CVaR；不要用 public leaderboard 反复调参（过拟合榜单）。
- **供应链：** safetensors、锁版本、锁 hash、扫描依赖；不加载 pickle。
- **手册缺口：** 5 轴中的位置/干扰物/背景、评测轮次/时限/控制频率仍需飞书手册公开后核实；本轮所有 deadline/μ 结论都是**参数化**的，不是定值。

## 11. 资源与时间线（粗排）

- **第 1 周：** 建 canonical schema + 本地 Eval-Replica；跑通 1 个教师 + 1 个学生。

## 12. 本轮最大风险 & 押注

**一句话：最大的风险是把"教师动物园的 oracle 上界"误当成"单模型学生的真实成功率"——许可、污染、路由误差和蒸馏差距中的任何一项，都可能把离线 +10pp 变成线上负迁移或直接取消资格；因此 UIP-19 必须与 UIP-16 同时上线，所有收益先按蒸馏差距打折，再用配对真机评测兑现。**

**→ 押注：UIP-16（SR-D2）× UIP-19（OSS-Gate）的"合规蒸馏闭环"，由 UIP-18 的置信下界做上线门、UIP-20 的末步转化决定算力去向。** 它同时回答了两个词：**成功率**要求我们按乘性边际收益分配；**开源生态**要求我们把多样性蒸成单模型，而不是在推理期集成。
