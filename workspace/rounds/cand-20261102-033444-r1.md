# 第 13 轮 · FRAME-RAG：把「物体 6D 位姿」换成「任务帧」，把「一次开环 chunk」换成「姿态键控记忆 + 确定性验证」

> 检索/复核日期：**2026-11-02（UTC）**。对象：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是第 12 轮 CHUNK-SERVO 的深化，不推倒它；三个灵感词是「姿态估计」「迭代验证」「论文创新点」。一句话：**上一轮把伺服接进了控制环，这一轮把伺服的目标从“物体 6D 位姿”降级为“任务帧”，把 33k 成功演示从“目标图库”升级为“姿态键控的动作记忆”，再用一个确定性验证器在同一 VLA checkpoint 的多个候选 chunk 之间做迭代选择。**

## 0. 先纠正上一轮的两个事实错误（这会改变方案）

1. **腕部相机不是没有内参**。上一轮说 `wrist_left/right.camera_params` 只有 `color/ir1/ir2`、没有内参；我逐数据集读 `meta/info.json` 后确认：`camera_params.wrist_left.color.camera_matrix` 是有的（HangCup 示例 fx≈436.41, fy≈435.92, cx≈323.92, cy≈242.93），`ir1/ir2` 也有（fx≈388.65）。缺的是**手眼外参**，不是内参。上一轮的 G0 门写错了；本轮把 G0 改成“手眼外参 + 任务帧可辨识性”。
2. **公开榜单不是实测**。`leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`；对 8 个模型 ×32 任务做 `step ~ success` 回归，8 条线全部 **R²=1.000000**，斜率 1.305–1.371；成功率出现 27.29%、27.85%、21.29% 等非 10% 整数倍；`runs.html` 的 256 条记录也是同样形态；`details.html` 的 32 个任务视频全部是“测试视频占位”。所以 **29.7% 是赛事方的预览/难度信号，不是可复现的 SOTA，也不是真实上限**。这直接决定了本轮把“迭代验证”当作一等公民：不能拿公开榜单做模型选择，必须自己搭验证阶梯。

这两个纠正一个让方案更容易（腕部可用），一个让方案更难（没有可信的公共分数）。本轮的方法就是围绕这两个纠正展开。

## 1. 上一轮的隐藏假设，以及它为什么会崩

CHUNK-SERVO 的核心是：

```text
VLA 出 30 步规划
→ 从 33k 演示检索“目标-夹爪相对位姿” T*_{target→ee}
→ 在线估计受器位姿 T^B_target(t)
→ 期望位姿 T^B_ee(t) = T^B_target(t) · T*_{target→ee}
→ 5 步一块做 IBVS/PBVS 修正
```

这条链条有一个隐藏假设：**在线能稳定估计受器的 6D 位姿**。但 32 个任务里，受器包括：

- 反光/透明的杯架、试管架、针管、药瓶；
- 小目标：网口、锁孔、拉链头、充电器插脚；
- 被夹爪/手臂遮挡的目标；
- 会被人移动的目标；
- 变形物体：毛巾、书包、耳机线。

对它们做完整 6D 位姿估计，既不必要也不可靠。**操作真正需要的不是“物体在 base 系的 6D 位姿”，而是“夹爪相对于一个局部任务帧的相对位姿”**。例如：

- 插网线只需要知道“网口平面 + 插入轴 + 卡扣方向”；
- 挂杯子只需要知道“挂钩平面 + 钩口方向”；
- 拉拉链只需要知道“拉链齿线 + 拉头位置”；
- 叠碗只需要知道“碗沿圆 + 碗轴”；
- 开锁只需要知道“锁面 + 钥匙孔轴”。

这些是**几何基元（平面/圆/线/槽）**，不是完整物体模型。它们可以从头双目点云 + 腕部图像里鲁棒地拟合，而且不需要 CAD、不需要类别级 3D 模型、不需要第二个学习模型。这就是本轮的第一个支点：**任务帧（task frame）取代物体 6D 位姿**。

## 2. 三个灵感词怎么落地

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **姿态估计** | 估计的是“任务帧”而非物体 6D 位姿：平面/圆/线/槽 + 夹爪相对位姿；头双目给米制深度，腕部给最后 1–2cm 的 2D 对齐；协方差显式传播 | 不训 6D 物体位姿网络；不假设透明/反光/变形物体可建模；不做类别级 CAD 检索 |
| **迭代验证** | 两层：①执行层——每个 5 步块重新估计任务帧、重新验证候选 chunk（receding horizon）；②实验层——L0 离线回放 → L1 仿真 → L2 单任务不计分通道 → L3 全量，配分层贝叶斯与预注册门 | 不用公开榜单做模型选择；不用 5 次 A/B 就宣称显著；不做“一次大提交”的赌博 |
| **论文创新点** | ①任务帧规范化让跨物体/跨位姿的动作 chunk 可检索；②确定性几何验证器让同一 VLA checkpoint 的 best-of-N 变成“合规的测试时扩展”；③小样本具身评测的分层贝叶斯验证协议 | 不把工程 trick 包装成新架构；不声称“首个 VLA + 伺服”；不依赖未公开的榜单分数 |

## 3. 新想法：FRAME-RAG（Frame-relative Retrieval-Augmented Generation）

一句话：**把 33k 成功演示切成“任务帧相对的动作 chunk”，建成姿态键控的记忆；在线用当前任务帧检索 top-K；让同一个 VLA checkpoint 采样 N 个候选；用一个确定性几何验证器选一个；每 5 步重验一次。**

### 3.1 离线：任务帧相对的动作记忆

对每个演示 episode 的每一帧：

1. 用头双目 + 已知内参/外参拟合任务帧 \(T^B_\mathcal{F}(t)\)（见 §4）。
2. 计算任务帧相对的夹爪位姿 \(g_t = (T^B_\mathcal{F}(t))^{-1} T^B_E(t)\)。
3. 取未来 H 步的动作 chunk \(A_{t:t+H}\)（数据集里同时有 joint 和绝对 EE 动作，API 的 `ee` 模式也是绝对 EE，可直接用）。
4. 记录相位 \(\phi_t\)、夹爪开度 \(s_t\)、质量权重 \(w_t\)（平滑度/时长/是否成功）。
5. 写入索引：键是 \((task, \phi, g_t, s_t)\)，值是 \(A_{t:t+H}\) + 局部目标图 + 质量。

规模估算：33,276 episodes × 约 500 帧 ≈ 1,660 万帧；只保留接触/关键相位（每 episode 30–60 帧）→ 约 100–200 万条；每条 30×21 float32 ≈ 2.5KB → 2.5–5GB；加目标图 ROI 后 <10GB。可离线构建，随提交包分发或预加载。

### 3.2 在线：姿态键控检索

当前观测估出 \(g_t\) 后，在 \((task, \phi)\) 分片里做最近邻：

\[
d(g,g') = \sqrt{ \frac{\| \log(g^{-1}g') \|^2}{\sigma^2} + \lambda_s (s-s')^2 + \lambda_v \|v-v'\|^2 }
\]

取 top-K（K=5–10）。检索是 CPU/FAISS，<10ms。

关键：**用任务帧相对位姿做键，而不是用物体身份或全局图像**。这样：

- 位置泛化：物体移动，\(T^B_\mathcal{F}\) 变，\(g_t\) 不变；
- 旋转泛化：物体转向，\(g_t\) 不变；
- 未见物体：只要任务帧几何同类（同类插座/杯架/拉链），\(g_t\) 不变；
- 背景/干扰物：只用局部 ROI 拟合任务帧，不用全局背景。

### 3.3 在线：同一 checkpoint 的 best-of-N + 确定性验证器

这是本轮最像“论文创新点”的部分，也是最需要工程验证的部分。

1. **候选生成**：
   - VLA 采样 N 个 action chunk（N=4–8），共享 VLM 的 KV cache，只对 DiT action head 做 N 次去噪；这是“同一模型多次采样”，不是第二个模型。**这是设计假设（C 级），需在 W0 用 WLA 的 action expert 实测“复用 VLM 特征/缓存后能否 cheap 地采样 N 次”；若不能，N 降到 2 或只在关键相位做 best-of-N。**
   - 检索到的 top-K 动作 chunk 作为**参照**（reference），不直接当策略执行；如果规则允许，也可以作为候选。
2. **确定性验证器**：对每个候选 A：
   - 前向运动学得到未来 EE 位姿 \(T^B_E(t+k)\)；
   - 任务帧相对 \(g_k = (T^B_\mathcal{F}(t))^{-1} T^B_E(t+k)\)；
   - 记忆流形距离 \(s_{\text{mem}}\)：预测轨迹到演示记忆流形的距离（DTW/最近邻）；
   - 自由空间 \(s_{\text{free}}\)：夹爪扫掠体 vs 头双目点云；
   - 平滑 \(s_{\text{smooth}}\)：jerk/加速度；
   - 进展 \(s_{\text{prog}}\)：沿任务帧插入轴/接近轴的进展；
   - 一致性 \(s_{\text{agr}}\)：与 N 个候选的中位数距离。
   - 加权和 \(S(A)\)，取 argmin。
3. **不确定性门控**：任务帧协方差大、或 top-2 分数差小于噪声 → 回退到 VLA 均值/保守伺服；不硬选。
4. **执行**：赢家按 5 步一块执行；每块重新估计任务帧、重新验证/重选（receding horizon）。VLA 规划异步，不阻塞 `get_action`。

为什么这是合规的：

- 验证器没有学习权重（前向运动学 + 点云 + DTW + 加权和）；
- 检索是非参数记忆，不是第二个策略；
- best-of-N 是同一 checkpoint 的多次采样；
- 只有 VLA 是学习模型。

边界：如果官方把“检索记忆”也算模型，退回 C1（只用检索做离线目标，不参与在线选动作）。

### 3.4 为什么不是“又一个视觉伺服”

VGM-VS（arXiv 2609.28312）已经证明：用预训练视觉几何模型 + 参考图 + 度量适配，可以在 USB-C/内存条插入上做到亚毫米、目标移动时 90–100%。VLA-Feedback（arXiv 2609.21022）已经证明：把扩散去噪的最后一步留作高频反馈，可以在动态任务上从 27.5% 提到 85%。D²-VLA（arXiv 2609.34792）已经证明：双频控制可以在 KV-cache 层做。CHUNK-SERVO 如果只是“VLA + 伺服”，很难说是新的。

FRAME-RAG 的差异在于：

- **不是伺服到一张参考图，而是检索到一组动作 chunk**：参考图只给“目标长什么样”，动作记忆还给“从当前相对位姿该怎么动”。这对接触阶段的“先退再进”“侧向让位”“旋转对齐”很关键。
- **不是单个候选的闭环，而是多个候选的验证**：伺服只能修正“已经选定的轨迹”，验证器能改“选哪条轨迹”。这对应 test-time scaling，而不是 control。
- **不是物体 6D 位姿，而是任务帧**：这使方法能覆盖透明/反光/小目标，且不需要 CAD。
- **不是训练新模型，而是把 33k 演示变成非参数记忆**：在单模型规则下，这是最便宜的数据杠杆。

### 3.5 论文创新点（可写、可测、可反驳）

| # | Claim | 可测指标 | 失败会怎样 |
|---|---|---|---|
| P1 | 任务帧规范化使跨物体/跨位姿的动作 chunk 可检索 | top-5 检索中几何有效 chunk ≥80%；相对位姿误差 ≤5mm/2°；跨物体留出集不崩 | 退回任务级固定相对目标；P1 不成立 |
| P2 | 确定性几何验证器能让同一 VLA 的 best-of-N 涨点 | 同 N 下 verifier > random > mean；N=1→4 的增益；延迟预算内 | 说明验证器信号不足；只保留伺服 |
| P3 | 分层贝叶斯 + 预注册门的验证阶梯能在 10 trials/task 下做可靠模型选择 | 后验可信区间宽度；决策错误率；与全量评测的一致性 | 退回简单配对 A/B；P3 降级为工程规范 |

这三条都不是“更大的模型”，而是“更好的表示、更好的测试时计算、更好的评测”。这正好对应榜单头部共享的瓶颈：最后 3 厘米、远程延迟、10 次 trial 的噪声。

## 4. 竞赛策略：先做“任务帧稳定”的任务

不是 32 个任务一起上。先做任务帧几何稳定、接触密集、失败发生在最后 3cm 的任务：

- **第一梯队（任务帧最稳）**：PlugInEthernet、DisconnectEthernet、PlugCharger、ArrangeTestTubes、HangCup、StackBowls、PaperCupStacking、Unlock、ZipUp、StoreCups。
- **第二梯队（任务帧中等）**：ToolboxStorage、OrganizeStationery、PackBag、StorePaddle、StoreEarphones、PackPhone、OrganizePencilCase、PourOutMedicine。
- **暂缓（任务帧不稳/变形/透明）**：FoldTowel、SyringeWaterTransfer、PackDoll、PlacePhotoFrame、SpellRobot、ConveyorSorting。
- **不投**：从零训 6B、完整世界模型、32 任务各训策略、30Hz 广域网伺服、6D 物体位姿网络。

先用单任务不计分通道做 5 个代表任务：PlugInEthernet（插入）、HangCup（挂）、ZipUp（拉链）、StackBowls（叠）、FoldTowel（负对照）。每个任务 5–10 次配对 A/B：baseline（WLA + chunk 30）vs FRAME-RAG（WLA + 检索 + 验证 + 5 步伺服）。通过标准：≥3/5 +10pp，FoldTowel 不回归 >5pp。

## 5. 风险与合规（本轮新增）

- **任务帧估计失败**：透明/反光/遮挡 → 协方差门控，回退 VLA/腕部 2D。
- **检索错配**：任务/相位过滤 + 位姿先验 + top-k 重打分；置信度低回退。
- **验证器误导**：离线校准 + 不确定性 + top-2 接近时回退；不让验证器单独决定安全关键动作。
- **best-of-N 延迟**：共享 KV cache；N 自适应（延迟高时 N=2）；异步规划。
- **单模型解释**：C1/C2/C3 三档合规；检索只做记忆/参照，验证器无学习权重。
- **过拟合公开榜单**：公开榜单是生成器，不做模型选择；只用自建验证阶梯。
- **10 trials/task 噪声**：分层贝叶斯 + 配对 + 预注册；不把 +1–2pp 当结论。

## 6. 一句话押注

**先用任务帧把“物体 6D 位姿”这个不可靠的中间量换掉，再把 33k 成功演示变成姿态键控的动作记忆，最后用确定性验证器在同一 VLA checkpoint 的多个候选中做迭代选择——在不新增学习模型的前提下，把最后 3 厘米从“伺服一条轨迹”升级为“验证多条轨迹”。**

# 第 13 轮产物 · FRAME-RAG 技术报告

> 检索/复核日期：**2026-11-02（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「FRAME-RAG」的工程化产物；它深化第 12 轮 CHUNK-SERVO，保留其双频执行与竞赛组合，把“物体 6D 位姿”替换为“任务帧”，把“单条轨迹的伺服”扩展为“多条候选的确定性验证”。

## 0. 结论与边界

### 0.1 一句话结论

公开榜单的 29.7% 是脚本生成的预览，不是实测上限；在这个前提下，最便宜、最合规、最可能涨点的创新不是再训一个大模型，而是：**用任务帧相对位姿把 33k 成功演示变成可检索的动作记忆，用同一 VLA checkpoint 采样多个候选，用无学习权重的几何验证器选一条，再用 5 步一块的伺服执行并在每块重验**。这把“最后 3 厘米”从“伺服一条轨迹”升级为“验证多条轨迹”。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、排行榜 JSON 直接核实 | 规则、API、33,276 eps、腕部内参、WLA `chunk_size=30`、榜单 29.7% |
| B | 我们在公开数据/网页上做的分析，可复现 | 榜单 `step~success` 回归 R²=1.000000、成功率非 10% 整数倍、256 条 run 记录同形态 |
| C | 设计假设，需 G0–G8 验证 | 任务帧检索 top-5≥80%、验证器 best-of-N 涨点、5 步伺服 +10pp |

### 0.3 本轮不做什么

- 不从零训 VLA/World Model；官方 WLA 已开源 6B 基座。
- 不做完整 sim-to-real 策略训练；数字孪生只做控制器风洞与验证器校准。
- 不做第二个学习模型/残差策略；验证器是确定性几何，检索是非参数记忆。
- 不做 6D 物体位姿网络；用任务帧基元 + 协方差门控。
- 不做力/触觉闭环；API 没有。
- 不做 30Hz 广域网伺服；用 5 步 chunk/双频。
- 不把公开榜单的任务排名当实测难度；它是生成器输出。
- 不做 32 个任务各一个策略；规则禁止且不泛化。

### 0.4 四个维度的切入点（对应任务要求）

| 维度 | 本轮切入点 | 具体做法 | 不做什么 |
|---|---|---|---|
| 数据 | 33k 成功演示 → 姿态键控动作记忆 | 任务帧相对 chunk 索引；关键帧；质量权重；跨物体/位姿检索 | 不重新标注 33k；不训 6D 位姿网络 |
| 模型架构 | 任务帧 + 确定性验证器 + 可选姿态辅助头 | VLA 仍是唯一学习模型；验证器/检索非参数；辅助头可选 | 不做第二个策略；不做完整世界模型 |
| 训练策略 | WLA action-head/LoRA 微调 + 离线校准 | 冻结 VLM；只训 action head；验证器权重离线校准 | 不从零训 6B；不做 RL 残差 |
| 接口工程 | 5 步 chunk + 双频 + 多端口共享 VLA | 异步规划；adapter；pivot/控制频率验证；p99 监控 | 不做 30Hz 广域网伺服；不猜 pivot 符号 |

## 1. 事实核对

### 1.1 比赛规则（A）

**身份确认**：官网、G1/Dex1、32 项桌面任务、`unibot_submission` 提交模板与 HF `unibot-v1-challenge-dataset` 均指向宇树 **UniBot 世界挑战赛**；不是其他同名 UniBot 项目。

官方参赛手册（飞书 docx，2026-11-02 通过 `r.jina.ai` 抓取；官网直连被 EdgeOne 拦截，HTTP 567）核实：

| 项 | 规则 |
|---|---|
| 模型 | 所有任务须基于**同一模型**完成，不得混合多个模型一起测试；模型类型不限（World Model、VLA 均可） |
| 任务 | 32 项桌面任务 |
| 次数 | 每任务 10 次独立运行 |
| 泛化 | 5 类各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰 |
| 时限 | 单次真机执行上限 **180 s** |
| 排名 | 先比 32 任务总平均成功率；相同看总平均步骤分；再相同看更早提交 |
| 部署 | 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态必须隔离 |
| 测试通道 | 另有**不计分的单任务测试通道**，可用于单任务成功率/步骤分验证 |

**约束**：FRAME-RAG 必须每端口独立、CPU 轻量、不抢 GPU；VLA 是唯一学习模型；任务帧拟合/检索/验证是确定性控制器或非参数记忆。

### 1.2 提交 API（A）

提交模板 README（2026-11-02 复核）给出：

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640** |
| 本体 | 双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str` |
| 动作空间 | `control_space` 仅 `"joint"` 或 `"ee"`，二者互斥 |
| 共享动作 | `action.left_gripper [1]`、`action.right_gripper [1]`、`action.pivot [7]` |
| EE 动作 | `action.left_ee_pose_gripper_base [6]`、`action.right_ee_pose_gripper_base [6]`（**绝对目标位姿**，xyz+rpy，base 系） |
| chunk | `action_chunk_size` ≥1，固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action` |
| token | `metadata.token` 握手校验一次；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile** |
| 监控 | 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分 |

**关键推论**：`action_chunk_size=30`、控制频率 30Hz 时，一次 `get_action` 之后有 **1 秒开环执行**；chunk 内没有新观测，也没有打断机制。控制频率未在 README 中写死；本报告默认 30Hz，必须在单任务通道实测。

## 2. 问题形式化

### 2.1 评分与不确定性

总分：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

320 trials 下，若 `p≈0.25`，单次标准误：

```math
\mathrm{SE}(S)\approx \sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

配对 A/B 的方差取决于任务内相关；若同一初始条件的 A/B 成功高度相关，配对差值方差可显著降低。报告必须给配对差值的 bootstrap 置信区间，而不是只报两个平均值。

人为干扰轴：

```math
\Delta S_{\mathrm{human}} = \frac{2}{10}\,\Delta p_h = 0.2\,\Delta p_h.
```

即 human 轴成功率 +10pp → 全局 +2pp。

### 2.2 任务帧与相对位姿

定义任务帧 \(\mathcal{F}\) 在 base 系的位姿 \(T^B_\mathcal{F}(t)\in SE(3)\)。它不是物体 6D 位姿，而是一个**局部几何坐标系**：

- 原点：任务相关的几何中心（孔心、钩口、拉链头、碗沿圆心、锁孔中心）；
- \(z_\mathcal{F}\)：插入/接近轴（孔轴、钩法向、碗轴、钥匙孔轴）；
- \(x_\mathcal{F}\)：横向对齐方向（卡扣方向、齿线方向、盘沿切线）。

夹爪相对任务帧：

```math
g_t = \left(T^B_\mathcal{F}(t)\right)^{-1} T^B_E(t)\in SE(3).
```

操作策略只依赖 \(g_t\)，不依赖物体在桌面上的绝对位置/朝向。期望夹爪位姿：

```math
T^B_E{}^d(t) = T^B_\mathcal{F}(t)\,\tilde g,
```

其中 \(\tilde g\) 是从成功演示检索/验证得到的相对目标。

### 2.3 姿态键控检索度量

把 \(g=(\rho,\theta)\in SE(3)\) 用对数映射表示（\(\rho=V^{-1}t\)，\(\theta=\log R\)）。定义加权距离：

```math
d(g,g') = \sqrt{
  \frac{\|\rho-\rho'\|^2}{\sigma_p^2}
  + \frac{\|\theta-\theta'\|^2}{\sigma_r^2}
  + \lambda_s (s-s')^2
  + \lambda_v \|v-v'\|^2
}.
```

- \(s\)：夹爪开度；
- \(v\)：局部视觉描述子（可选；优先用任务帧几何，不用全局外观）；
- \(\sigma_p,\sigma_r\)：由任务帧协方差和演示噪声标定。

检索在 \((task,\phi)\) 分片内做，避免“插网线”匹配到“拔网线”。

### 2.4 验证器评分

对候选动作 chunk \(A=\{a_k\}_{k=0}^{H-1}\)：

1. 前向运动学/相对动作 compose 得 \(T^B_E(t+k)\)。
2. 任务帧相对 \(g_k=(T^B_\mathcal{F}(t))^{-1}T^B_E(t+k)\)。
3. 分数：

```math
S(A)= w_m s_{\mathrm{mem}}(A)
    + w_f s_{\mathrm{free}}(A)
    + w_s s_{\mathrm{smooth}}(A)
    + w_p s_{\mathrm{prog}}(A)
    + w_a s_{\mathrm{agr}}(A).
```

其中：

- \(s_{\mathrm{mem}}\)：预测轨迹到演示动作记忆流形的距离（DTW 或终点最近邻 + 平均距离）；
- \(s_{\mathrm{free}}\)：夹爪扫掠体与头双目点云的穿透/最近距离；
- \(s_{\mathrm{smooth}}\)：jerk/加速度；
- \(s_{\mathrm{prog}}\)：沿 \(z_\mathcal{F}\) 的进展（插入/接近），越大越好，取负；
- \(s_{\mathrm{agr}}\)：与 N 个候选的中位数距离，抑制离群。

选 \(A^*=\arg\min_A S(A)\)。权重 \(w\) 在离线留出集/仿真上校准，不硬编码。

### 2.5 姿态协方差传播

任务帧估计有协方差 \(\Sigma_\mathcal{F}\)。相对位姿的一阶传播：

```math
\Sigma_g \approx J_g \Sigma_\mathcal{F} J_g^\top + \Sigma_{\mathrm{calib}},
```

其中 \(J_g\) 是 \(g=(T^B_\mathcal{F})^{-1}T^B_E\) 对 \(T^B_\mathcal{F}\) 的雅可比，\(\Sigma_{\mathrm{calib}}\) 是手眼/外参标定残差。用途：

- 协方差大 → 降低 \(w_m\)，提高回退概率；
- 协方差大 → 不启用高增益 IBVS；
- 协方差大 → 触发“主动窥视”（可选）。

### 2.6 接口时间模型

设：

- \(f_c\)：evaluator 控制频率（假设 30Hz）；
- \(H_c\)：提交的 `action_chunk_size`；
- \(\tau\)：网络 RTT + 推理 + 图像传输的等效延迟；
- \(T_{\mathrm{fb}}\)：从“世界变化”到“策略看到变化”的反馈周期。

```math
T_{\mathrm{fb}} \approx \frac{H_c}{f_c} + \tau.
```

| 场景 | \(H_c\) | \(f_c\) | \(\tau\) | \(T_{\mathrm{fb}}\) | 评价 |
|---|---:|---:|---:|---:|---|
| 官方 WLA 默认 | 30 | 30 | 50ms | **1050ms** | 接触段基本开环 |
| 本方案保守 | 5 | 30 | 50ms | **217ms** | 可做 1–2 次接触修正 |
| 本方案乐观 | 5 | 30 | 20ms | **187ms** | 需低 RTT |
| 本方案高延迟 | 5 | 30 | 150ms | **317ms** | 增益降档 |
| 低控制频率 | 5 | 10 | 50ms | **550ms** | 改 \(H_c=3\) 或只做 PBVS |
| 极低延迟 | 3 | 30 | 20ms | **120ms** | 动态任务可用 |

**结论**：\(H_c\) 必须按实测 \(f_c\) 和 \(\tau\) 选；不能把 30 步默认值直接搬到远程 API。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)       │
                    │  ├─ task-frame estimator (stereo)    │
                    │  ├─ pose-keyed memory (FAISS)        │
                    │  ├─ deterministic verifier           │
                    │  ├─ visual servo (IBVS/PBVS)         │
                    │  ├─ plan cache (30-step VLA plan)    │
                    │  └─ action adapter (WLA 54D → API)   │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared VLA server (GPU)            │
                    │  UnifoLM-WLA-1.0 / VLA-0, 30-step   │
                    └─────────────────────────────────────┘
```

- 每个端口一个 `PolicyService` 实例，独立 `reset()`、独立 plan cache、独立 goal/verifier 状态。
- 任务帧拟合、检索、验证是 CPU 线程，不阻塞 websocket；VLA 请求异步、可批处理。
- 共享 VLA server 用 session ID 区分端口；模型权重只有一份，不违反单模型。
- GPU 6B bf16 约 12GB；一张 24GB/40GB GPU 可服务多个端口，具体并发取决于 batch 和序列长度。

**帧/TCP 风险**：WLA 的 EE 帧与挑战赛的 `*_ee_pose_gripper_base` 帧可能差一个 TCP/夹爪长度偏移；必须用 `example_env.py` 的观测和真实数据做一次手眼/工具坐标校准（平移 ≤1cm、旋转 ≤2°）。

**`pivot` 风险**：7 维语义在 README 中只写“Lower-body / pivot target”，没有逐维定义；这是 adapter 的第一验证项。若语义不匹配，先返回全零 pivot（保持下身体不动），只验证双臂；不要猜符号。

### 3.3 `get_action` 伪代码

```python
class FrameRagPolicy:
    def get_action(self, obs):
        self._tick(obs)

        # 1) 任务帧估计（CPU，可用缓存）
        frame = self.task_frame.estimate(obs)          # T^B_F(t), Sigma_F
        if frame is None:
            return self._fallback_vla(obs)

        # 2) 视觉伺服目标 + 姿态键控检索
        goal = self.memory.query(obs, frame, k=5)      # top-K chunks + g targets
        self._maybe_request_plan(obs, frame)

        # 3) 候选：VLA best-of-N（共享 KV cache）+ 检索参照
        if self.plan is None:
            candidates = self._cold_start(obs)
        else:
            candidates = self._vla_samples(obs, n=self.N) + goal.chunks

        # 4) 确定性验证器
        best, score, unc = self.verifier.select(candidates, frame, obs)
        if unc > self.theta_u or score.margin < self.theta_m:
            best = self._safe_fallback(candidates, frame)

        # 5) 5 步执行 + 伺服修正
        a_ff = best[: self.H_c]
        delta = self.servo.compute(obs, frame, goal)
        a_cmd = compose_relative(a_ff, delta)

        # 6) 每块推进；plan 过期则异步重规划
        self.plan_idx += self.H_c
        if self.plan_idx >= len(self.plan or []):
            self.plan = None
        return self.adapter.to_api(a_cmd, obs, self.token)
```

`_maybe_request_plan`：

```python
def _maybe_request_plan(self, obs, frame):
    if self._future is not None and not self._future.done():
        return
    if self._future is not None:
        self.plan = self._future.result()
        self.plan_age = 0
        self._future = None
    if self.plan is None or self.plan_age >= self.plan_ttl:
        snapshot = copy_obs(obs)
        self._future = self.executor.submit(self.vla.predict, snapshot)
```

规则：

- VLA 永远不阻塞 `get_action`（除冷启动）；plan 过期就用旧 plan + 伺服/验证。
- 每个 chunk 只做一次验证；验证失败不影响返回合法动作。
- 任何异常 → 返回上一组合法 chunk 或安全 hold；绝不返回 NaN/错误形状。

### 3.4 离线动作记忆构建

```python
for episode in demos:
    for t in keyframes(episode):               # 接触前/接触中/释放前
        F = estimate_task_frame(episode, t)     # 头双目 + 任务先验
        if F is None: continue
        g = inv(F.T_base) @ episode.ee[t]       # 任务帧相对夹爪
        A = episode.actions[t:t+H]              # 绝对 EE / joint
        s = episode.gripper[t]
        w = quality(episode, t)                 # 平滑/时长/成功
        index.add(task=episode.task, phase=phase(t),
                  key=(g, s), value=(A, F.wrist_roi, w))
```

关键帧选择：

- 接触任务：首次接触前 1–3 帧、接触稳定后 1 帧；
- 挂/叠/插入：目标进入腕部视野且夹爪距离 <5cm；
- 拉链/锁：夹爪咬合前；
- 变形任务：不建精确任务帧，只建相位/语义目标，验证器不启用。

### 3.5 在线检索/验证/执行

```text
1. 估计 T^B_F(t)，协方差 Sigma_F
2. 若 Sigma_F 过大 -> 回退 VLA / 腕部 2D
3. 在 (task, phase) 分片检索 top-K g
4. VLA 采样 N 个 chunk（共享 KV cache）
5. 对每个候选：FK -> g_k -> s_mem/s_free/s_smooth/s_prog/s_agr
6. 选 S 最小；若 top-2 差 < theta_m -> 回退 VLA 均值
7. 执行 5 步；每块重估/重验；VLA 异步重规划
```

**C 级假设**：第 4 步“共享 KV cache 采样 N 次”依赖 WLA 的 action expert 能复用 VLM 特征/缓存；若实测不能，则 N 降到 2，或只在接触相位做 best-of-N。这是 W0 的第一个工程验证项。

### 3.6 状态机

```text
INIT ──first obs──▶ PLAN ──plan ready──▶ VERIFY
  ▲                   ▲                    │
  │                   │                    ├─ pose stable ──▶ SERVO
  │                   │                    │                   │
  │                   │                    │                   ├─ d_t < d_c ──▶ CONTACT
  │                   │                    │                   │                 │
  │                   │                    │                   │                 └─ released ──▶ SERVO
  │                   │                    │                   │
  │                   └── replan ◀── RECOVER ◀── edit_score > θ_e
  │                                      │
  └──────────────────────────────────────┘
任意状态 ──task success / max steps──▶ DONE
```

- `VERIFY`：任务帧稳定时选候选；不稳定时回退。
- `SERVO`：正常接近，PBVS 主导，IBVS 辅助。
- `CONTACT`：`d_t < d_c` 或相位=接触；法向增益降低、切向保留；`r_grasp` 突变 → 滑移处理。
- `RECOVER`：编辑检测触发；先停，再重定位；目标可见 → 更新任务帧；不可见 → VLA 重规划。
- `DONE`：任务成功/最大步数；清理状态，等待 `reset()`。

## 4. 姿态估计与任务帧

### 4.1 头双目深度

头双目已校正，基线 \(b=0.0582526\) m，焦距 \(f\approx282\) px。视差 \(d=u_L-u_R\)，深度：

```math
Z=\frac{fb}{d}.
```

| 距离 | 视差 | 深度误差（\(\sigma_d=0.25\)px） |
|---:|---:|---:|
| 0.3 m | 54.8 px | 1.4 mm |
| 0.5 m | 32.9 px | 3.8 mm |
| 0.8 m | 20.6 px | 9.7 mm |
| 1.0 m | 16.4 px | 15.2 mm |

结论：头双目在 0.3–0.5 m 工作距离上可给毫米级深度，足够 3–5cm 的接近和轴对齐；最后 1–2mm 的插入由腕部 IBVS 完成。

### 4.2 腕部内参与手眼标定

- 内参已知（`color.camera_matrix`，fx≈436），不需要棋盘格。
- 手眼外参 \(T^E_C\) 未知：用数据集中的腕部图像 + EE 位姿做 \(AX=XB\)，或用已知 URDF 的夹爪模型做 PnP。
- 在线可用 `state_d435` 恢复头相机外参；腕部外参一旦标定，按机器人/批次固定。
- 校验：重投影误差 ≤5px；用夹爪已知宽度/指尖距离做尺度校验。

### 4.3 基元拟合

| 基元 | 方法 | 用途 | 失败信号 |
|---|---|---|---|
| 平面 | RANSAC + 法向一致性 | 桌面/锁面/网口面 | inlier <30% |
| 圆/椭圆 | 2D 拟合 + 3D 圆拟合 | 杯口/碗沿/试管孔/瓶口 | 残差 >2mm |
| 直线/槽 | Hough/点云主成分 | 拉链齿线/网口卡扣/槽 | 方向方差大 |
| 矩形/孔 | 轮廓 + 四边形拟合 | 网口/插座/盒口 | 角点不稳 |
| 轴 | 平面法向 + 孔轴 | 插入轴 | 两视图不一致 |

任务帧构造（示例）：

| 任务 | 原点 | \(z_\mathcal{F}\) | \(x_\mathcal{F}\) |
|---|---|---|---|
| PlugInEthernet | 网口中心 | 插入轴（指向孔内） | 卡扣方向 |
| HangCup | 钩口中心 | 钩口法向 | 杯架横梁方向 |

### 4.4 协方差与可辨识性

协方差来源：

- 双目视差噪声（深度随 \(Z^2\) 增长）；
- 基元拟合残差（RANSAC 内点协方差）；
- 手眼/外参标定残差；
- 遮挡导致的偏观测。

用 bootstrap/雅可比把像素/点云噪声传播到 \(T^B_\mathcal{F}\)，再传播到 \(g\)。可辨识性条件：

1. 任务帧在头双目或腕部视野内；
2. 基元内点 ≥ 阈值（平面 30%、圆 20 点、线 15 点）；
3. 双视图/多帧一致性（轴方向差 <3°）；
4. 协方差迹 < 阈值；
5. 任务属于刚体接触类。

任一条不满足 → 回退 VLA 开环或腕部 2D 粗对齐；不硬做 IBVS。

### 4.5 回退策略

```text
if task_frame_valid and wrist_features_valid:  PBVS + IBVS
elif task_frame_valid:                          PBVS
elif wrist_features_valid:                      IBVS (with prior depth)
else:                                            VLA open-loop
```

回退不是失败：它保证 `get_action` 永远返回合法动作；验证器的边际收益在任务帧稳定任务，其他任务回退 VLA 是预期行为。

## 5. 迭代验证协议

### 5.1 验证阶梯

| 层 | 数据/环境 | 目的 | 通过标准 |
|---|---|---|---|
| L0 | 离线留出演示（按 session/物体/背景划分） | 任务帧/检索/验证器是否可信 | top-5 几何有效 ≥80%；验证器 top-1 ≥70% |
| L1 | MuJoCo/IsaacLab + G1 URDF | 伺服/验证器稳定域；扰动 | 横向 ≤2mm、深度 ≤3mm、2s ≥95% |
| L2 | 官方单任务不计分通道 | 真机 A/B | ≥3/5 任务 +10pp；负对照不回归 |
| L3 | 官方 32×10 全量 | 最终排名 | 无端口串扰；p99 ≤150ms；内存不涨 |

### 5.2 分层贝叶斯模型

对任务 \(t\)、trial \(j\)：

```math
y_{t,j}\sim \mathrm{Bernoulli}(p_t),\qquad
\mathrm{logit}(p_t)=\mu+\delta_t+\beta^\top x_{t,j},
```

```math
\delta_t\sim\mathcal{N}(0,\tau^2),\qquad
\mu\sim\mathcal{N}(0,1),\qquad
\tau\sim\mathrm{HalfNormal}(0.5).
```

- \(\delta_t\) 是任务随机效应，部分池化；
- \(x_{t,j}\) 是泛化类型/干扰协变量；
- 处理效应 \(\Delta\) 可设为共享或任务特定；
- 用后验 \(P(\Delta>0)\) 和 95% credible interval 做决策，而不是只看均值。

### 5.3 序贯停止与分配

- 每个任务先做配对 A/B（同初始条件）；
- 序贯停止：当 \(P(\Delta_t>0\mid data)>0.95\) 或 <0.05，或达到最大 10 对，停止；
- 剩余 trial 分配给“高不确定性 × 高期望增益”的任务；
- 预注册停止规则，避免 p-hacking。

### 5.4 门 G0–G8

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | 手眼外参 + 任务帧可辨识？ | 重投影 ≤5px；任务帧误差 ≤5mm/2°；内点率 ≥70% | 只用头双目 PBVS；腕部仅 2D 粗对齐 |
| G1 | 姿态键控检索可信？ | top-5 含几何有效 chunk ≥80% | 改用任务级固定相对目标 |
| G2 | 验证器排序可信？ | 对 GT vs 扰动 chunk 的 top-1 ≥70% | 只保留伺服；验证器降级为软先验 |
| G3 | 仿真收敛/扰动通过？ | 横向 ≤2mm、深度 ≤3mm、2s ≥95%；RTT 0–150ms 稳定 | 降增益/加 chunk；只做 PBVS |
| G4 | 真机单任务涨点？ | 3/5 任务 +10pp；负对照不回归 >5pp | 不提交验证器版本 |

## 7. 竞赛策略

### 7.1 失败模式分诊

| 失败模式 | 典型任务 | 该投什么 | 不该投什么 |
|---|---|---|---|
| 最后接触/插入/挂/叠/拉链/锁 | PlugInEthernet、HangCup、ZipUp、StackBowls、Unlock、ArrangeTestTubes、ToolboxStorage | 任务帧 + 检索 + 验证 + 伺服 | 更大 VLA、更多语义数据 |
| 位置/人为干扰 | 5 类泛化轴；human_1/4 | 重定位 + 恢复 + 相对目标 | 固定轨迹、开环 chunk |
| 背景/干扰物/未见物品 | FruitSorting、ColorArrangement、OrganizeTools | 任务帧局部 ROI + 检索（任务帧相对） | 纯几何伺服（对语义无效） |
| 变形/语义/长程 | FoldTowel、PackBag、SpellRobot、ConveyorSorting | VLA 基座 + 任务数据 | 任务帧/6D 物体位姿 |

### 7.2 任务组合

- **第一梯队（任务帧最稳，先做）**：T01 HangCup、T05 DisconnectEthernet、T10 PlugCharger、T12 Unlock、T13 ArrangeTestTubes、T19 ZipUp、T20 PaperCupStacking、T25 StoreCups、T26 PlugInEthernet、T27 StackBowls。
- **第二梯队（任务帧中等）**：T09 ToolboxStorage、T17 OrganizeStationery、T18 PackBag、T23 StorePaddle、T28 StoreEarphones、T29 PackPhone、T31 OrganizePencilCase、T14 PourOutMedicine。
- **暂缓（任务帧不稳/变形/透明/动态）**：T03 PackDoll、T07 PlacePhotoFrame、T16 FoldTowel、T22 SpellRobot、T24 ConveyorSorting、T32 SyringeWaterTransfer。
- **负对照**：FoldTowel，用来检测验证器/伺服是否伤害语义/变形任务。

组合规则：

```text
priority_t = q_t * Δ_t / cost_t
```

- `q_t`：失败发生在最后 3 厘米的比例（先用语义先验，单任务通道后更新）；
- `Δ_t`：验证器/伺服条件增益（A/B 差值）；
- `cost_t`：工程/评测成本（任务帧/标定/调参）。

先做第一梯队中 `q_t` 最高、`cost_t` 最低的 3–5 个；不要一次铺 10 个。

### 7.3 单任务通道协议

| 项 | 设计 |
|---|---|
| 任务 | PlugInEthernet、HangCup、ZipUp、StackBowls、FoldTowel |
| 次数 | 每任务 5–10 次 A/B（baseline vs FRAME-RAG） |
| 初始条件 | 同一位置/背景；尽量配对 |
| 指标 | 成功率、步骤分、耗时、p99 延迟、恢复次数 |
| chunk | 先固定 5；通过后扫 3/8 |
| 通过 | ≥3/5 任务 +10pp；FoldTowel 不回归 >5pp |
| 失败 | 不提交 FRAME-RAG 版本；只保留离线分析 |

统计：

- 配对差值 `Δ_t = p_on - p_off`；5 次/任务只能看方向，不能看显著性；
- 汇总 5 任务用 bootstrap + 分层贝叶斯；
- 若 CI 跨 0，继续测或放弃；不要用 +1–2pp 做结论。

### 7.4 边际收益与预算

| 方案 | 成本（估算） | 预期收益 | 建议 |
|---|---|---|---|
| 官方 WLA 直接适配 | 1–2 人周 | 基线；可能 20–30% | 必做；先锁基线 |
| WLA action-head 微调 | 2–3 GPU 周 + 1 人周 | +1–3pp（未知） | 做；但不要指望它解决最后 3cm |
| FRAME-RAG（任务帧+检索+验证+伺服） | 4–6 人周 + 1–2 GPU 周 | 第一梯队 +10–15pp → 全局 +3–6pp；human +1–2pp | 主投 |
| 完整世界模型 | 8+ GPU 周 | 不确定；延迟更差 | 不做 |
| 32 任务各训策略 | 规则禁止 | — | 不做 |

收益算术：

- 第一梯队 10 任务各 +10pp → `10/32×10=+3.1pp`；各 +15pp → +4.7pp；
- human 轴 +10pp → +2pp（20% 权重）；
- 保守合计 +4–6pp；乐观 +8–10pp；
- 若只有 5 个任务生效，+1.6pp + human +2pp ≈ +3.6pp。

这些是设计目标，不是承诺；G4/G8 不过就不提交。

### 7.5 提交节奏

1. **W0**：官方 WLA + API adapter + chunk 30 基线；单任务通道跑 1 个任务，确认接口/`pivot`/token/控制频率。
2. **W1**：安全基线提交（若允许多次）；锁“更早提交”tie-break。
3. **W2–W3**：任务帧/手眼标定/离线检索；L0/G0/G1。
4. **W4–W5**：验证器/仿真；L1/G2/G3。
5. **W6**：单任务 A/B；L2/G4/G5/G6。
6. **W7**：全量干跑；L3/G7。
7. **W8**：最终提交；保留回滚开关。

若只允许一次提交：跳过 W1，W7 后再交；不要用正式 320 trials 做未验证的 A/B。

### 8.2 深挖：N1–N4

**N1 任务帧姿态**

- 动机：完整 6D 物体位姿在透明/反光/小目标/遮挡下不可靠；操作只需要“孔轴/平面/齿线”这些局部量。
- 差异：不是 6D 位姿网络，不是 CAD 检索；是几何基元 + 协方差 + 夹爪相对位姿。
- 可行性：刚体任务高；透明/变形任务低，直接回退。
- 资源：头双目（已标定）、腕部内参（已有）、手眼外参（N5）、CPU。
- 步骤：32 任务帧定义 → 基元拟合 → 重投影验证 → 协方差标定 → 单任务通道。
- 风险：基元歧义（圆 vs 椭圆）、遮挡、标定漂移；用多帧一致性 + 协方差门控。

**N2 姿态键控动作记忆**

- 动机：33k 成功演示是最大的免费资产；VLA 微调只用了其中一部分，测试时完全没用。
- 差异：RoboTok（2609.03199）用 actor-centered 3D hand trajectory 检索互联网视频；RobMRAG（2603.00500）检索物体原型/接触帧；本项检索**同 embodiment 的动作 chunk**，键是**任务帧相对位姿**，用于**验证/参照**而非直接执行。
- 可行性：高；FAISS top-K <10ms；存储 <10GB。
- 资源：演示数据、存储、CPU。
- 步骤：关键帧 → 任务帧 → \(g_t\) → 索引 → 留出集评测 → 在线 top-K。
- 风险：演示风格差异、动作空间转换（joint vs EE）、任务帧误差。

**N3 确定性验证器 + best-of-N**

- 动机：伺服只能修一条轨迹；接触失败常常是“选错轨迹”（先撞了、退不够、转错方向）。
- 差异：VGM-VS 是单轨迹 PBVS；VLA-Feedback 是反馈去噪；RTC 是异步执行；本项是**多候选几何验证**。
- 可行性：中高；关键是 DiT head 采样 N 次的成本（C 级假设：可复用 VLM 特征/KV cache；需 W0 实测），以及验证器权重校准。
- 资源：1 GPU、CPU、仿真。
- 步骤：实现 FK/点云/DTW → 离线排序评测 → 仿真 N 消融 → 真机 A/B。
- 风险：验证器误排、延迟、单模型解释；用不确定性门控 + 回退。

**N4 迭代验证阶梯**

- 动机：公开榜单是 `gen_leaderboard.py` 生成的；10 trials/task 的 SE≈2.4pp；不能拿榜单做模型选择。
- 差异：常规做法报平均；本项用分层贝叶斯部分池化 + 序贯停止 + 预注册门。
- 可行性：高。
- 资源：单任务时段、全量时段、统计脚本。
- 步骤：预注册 → L0/L1 → L2 配对 → L3 全量 → 后验报告。
- 风险：时段有限、任务非平稳、p-hacking；用预注册和 blinded analysis。

| best-of-N 延迟 | timeout/排名降 | 共享 KV cache；N 自适应；异步规划；p99 门 |
| 手眼外参漂移 | 腕部伺服偏移 | 每机器人重标定；夹爪 PnP 自标定；误差大关伺服 |
| 单模型解释 | 被判第二个模型 | C1/C2/C3；检索只做记忆/参照；验证器无学习权重 |
| 公开榜单误导 | 过拟合预览 | 不做模型选择；自建 L0–L3 |
| 10 trials 噪声 | 假阳性 | 配对 + 分层贝叶斯 + 预注册 |
| `pivot` 语义不一致 | 动作被拒/机器人不动 | 先零 pivot 回退；单任务通道验证 |
| 提交次数限制 | 无法多次 A/B | 邮件确认；单任务通道先验证 |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组；相邻帧不跨 split |
