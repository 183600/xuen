## 1. 直觉与动机

### 灵感 1（论文创新点 → 创新点不是模块，是「可证伪的声明」）
直觉：前两轮清单越写越长，但审稿人会问：哪一条是**新知识**，哪一条只是把公开技巧堆上去？模块（增广、检索、恢复）本身不构成论文创新点，除非它能回答一个**可被实验否定的问题**。真正稀缺的不是想法，而是想法的**可检验形式**：声明、强基线、证伪实验、预期效应量、对应计分轴。由此得到本轮第一纪律（PR6）：不能写成可证伪声明的，降级为工程项。反直觉点：**把清单变短（更少但更硬）比变长更像论文创新。**

### 灵感 2（续航能力 → 每一集都有一块有限的「恢复预算」）
直觉：长程多物体任务（OrganizeBookshelf、PackBag、ToolboxStorage、StoreCups…）的失败很少是「某一步不会」，而是**误差复利**：每个开环 chunk 花掉一点纠错余量，直到越过不可恢复边界（物体掉落、出工作空间、任务状态错乱）。把它想成电池：每集开始时有一块「恢复预算」，开环执行耗电、纠正动作回一点电；分数不是「每步多准」，而是「能否在电量耗尽前做完」。F20 进一步说明：底座几乎不动，机器人不能靠「走过去」充电——预算只能靠手臂/夹爪的纠正行为赚回。反直觉点：**多数队伍优化每步油耗（action accuracy），但计分的是续航（不抛锚地跑完全程）。**

### 灵感 3（两者合流 → 论文主贡献是一条「续航定律」，模块是它的工程推论）
直觉：若「续航」只是比喻，它没有价值；只有当它能被测量、并**比现有指标更好地预测成败**，它才是论文创新点。于是把「论文创新点」落到一个可证伪的主声明：
**H1：在 chunk 化开环 VLA 中，episode 成败由「沿轨迹的最小恢复预算」支配，而非由平均每步动作误差支配；且失败可按预算曲线归因为「续航受限」或「能力受限」两类。**
若 H1 被离线实验否定（预算不比动作误差更能预测成败），I10–I12 全部降级为工程优化；若成立，则数据侧（I11）与控制侧（I12）共享同一目标函数。反直觉点：**先证伪一个诊断定律，再谈模块——这才是「论文创新点」的正确顺序。**

### 严谨定义（把「续航」变成可计算量）
- **任务相关偏差**：成功示教按进度坐标 DTW 对齐；对在线状态 s_t（进度 p_t），`d_t = min_{τ:|τ−p_t|≤δ} ‖φ(s_t) − φ(s*_τ)‖`，其中 φ = EE 位姿 ⊕ 夹爪开口 ⊕ 物体相对几何（视觉嵌入）。
- **成本到终点**：`c(s)` = 从 s 到成功的期望剩余步数（由成功示教回归的 progress / time-to-go 头）。
- **时间余量**：`b_t = (T_max − t) − c(s_t)`。
- **可存活裕度**：`g(s) = P(success | s)`（成功/近失败 rollout 训练并校准的分类器）。
- **恢复预算**：`B_t = (b_t / b_0) · g(s_t)`（b_0 为初始余量；`B_t ≤ 0` 即越过**不可恢复点 PNR**）。工程化标量，可替换为二维 `(b_t, g_t)` 前沿；关键是它必须能在离线被估计。
- **任务续航曲线**：`S_π(t) = P(min_{u≤t} B_u > 0)`；续航 `E_π = (1/T_max)∫ S_π(t) dt`，同时报告 PNR 分布。
- **失败归因**：`t_fail` = 首个 `B_t ≤ 0` 时刻。若 `t_fail` 前 B 单调缓降（|dB/dt| 低于阈值）→ **续航受限**（交给 I10/I11/I12）；若单个 chunk 内 B 突降 → **能力受限**（交给 I1/I2/I5/I3）。
- **续航感知目标**：最大化 `E_π`（或 `min_t B_t`），而非平均动作误差。与计分对齐：成功 = 存活到完成；超时步骤分 = 存活期间累计进度。

## 2. 痛点修订

- 新增 **P11 长程误差复利无诊断**：现有评测只有成败/总分，没有「何时、为何不可恢复」的中间量，长程任务无法定位该补数据还是补控制。
- 新增 **P12 恢复无预算计量**：I5 的恢复是「检测到偏离就纠」，会**过纠**（高预算时打断正常执行）或**欠纠**（低预算时来不及），缺少统一触发判据。
- 新增 **P13 服务长时退化**：320 集 × N 端口的评测是长跑；延迟爬升、显存碎片、热降频会让**后段任务**系统性变差，直接伤平均分。
- P8 补充：F21 表明空抓/重抓已在示教分布内，恢复数据不必从零发明，只需按「预算临界」重采样。

## 3. 研究问题（本轮立项 Q13–Q16）

- **Q13（续航可测性）**：仅用接口可见量（RGB、EE、夹爪开口）能否稳定估计 B_t？B_t 对成败的预测力（AUROC/校准）能否超过平均动作误差？
- **Q14（失败归因）**：续航受限 vs 能力受限的离线判别阈值如何定？两类失败在 32 任务上的比例，是否决定 I1/I2 与 I10/I12 的投入配比？
- **Q15（临界态数据）**：匹配样本量下，「临界态 + 预算标注」的恢复示教是否比均匀扰动更省数据地提升恢复成功率？
- **Q16（反馈预算）**：固定/半固定 `T_a` 下，按续航曲线做**任务组合**的 chunk 长度选择，是否比全局默认 `T_a` 在长程子集上更优？预算门控能否避免过纠？

## 4. 设计原则（新增 PR6/PR7）

- **PR6 可证伪贡献律**：每条创新点必须写成 {声明, 机制, 强基线, 证伪实验, 预期效应量, 计分轴}；缺任一项 → 记为工程项，不占「论文创新点」名额。
- **PR7 续航守恒律**：纠正/重抓是有限预算；只有当「期望成功增益 > 预算成本（时间 + 状态扰动）」时才触发。推论：高预算时**不纠**也是正确动作（抑制过纠）。
- PR1–PR5 保留（PR5 数据杠杆律继续约束 I11 合成数据）。

## 1. 创新点清单（每点：动机 / 差异 / 可行性 / 资源 / 步骤 / 风险 / 证伪）

### I1 考纲校准五轴增广引擎 ★★★★★（维持 v2）
- **动机**：计分的 320 次真机评测每次都在 5 轴上偏离训练分布（P2），泛化缺口是全局乘性损失。
- **差异**：用官方考纲卡把增广参数分布对准计分轴，把「零样本泛化」转化为「分布内泛化」，而非盲目随机化。
- **可行性/资源**：高；考纲卡 = LLM 解析 wiki + 人工校对（32×~10min）；分割/inpainting 1×24GB GPU，增广输出 ≈2TB。
- **步骤**：①32 张考纲卡；②背景/干扰物轴放量；③外观/位置轴 L0 先行；④剂量-响应定档；⑤轴间析因。
- **风险**：考纲卡与真实评测偏差；位置重拼接物理不可行（L0「不可行动作占比」>5% 即降级为平移不变增广）。
- **证伪**：在留出集上，考纲校准增广的 B 曲线下面积应显著优于盲目随机增广（否则退回 v1.0）。

### I2 数据引擎 2.0：110 语料孪生迁移 + 加权共训 ★★★★★（维持 v2，加保留指标）
- **动机**：单模型平均分被最弱任务支配（P1）；示教语料与质量双重浪费（P8）。
- **差异**：孪生任务定向入训 + patch 官方 loader 的族级权重（官方 weight 不生效）+ 示教质量 per-episode 加权。
- **本轮新增**：报告**保留续航**——加入新语料/新任务后，旧任务 `E_π` 不下降（防灾难遗忘），作为「续航」在训练侧的对应物。
- **可行性/资源**：高（frozen-VLM/LoRA 单卡起步；全参 action expert 4–8 卡）；孪生子集 ≈1–2TB + 32 任务 ≈2TB。
- **步骤**：①孪生表；②下载子集；③loader patch + batch 频率单测；④首轮共训；⑤族级 L0 验证正迁移后放量。
- **风险**：孪生任务动态相反导致负迁移（家族级 L0、低权重起步、退步即裁剪）；跨集 schema 需 adapter。
- **证伪**：若保留续航显著下降（旧任务 `E_π` 掉 >5%），族级权重退回更保守档。

### I3 接触任务族关键点视觉伺服回退 ★★★★（维持）
- **动机/差异**：插入/对齐段（PlugCharger、PlugInEthernet、DisconnectEthernet、Unlock、SyringeWaterTransfer、ZipUp）在 chunk 盲执行时最易卡死；关键点开放词汇检测 + 几何伺服 + 触发滞回 + 低置信回退，作为「能力受限」失败的控制侧补丁。
- **可行性/资源**：中；开放词汇检测零训练起步；1×24GB GPU，1 人周。
- **风险**：混合推理的单模型边界需书面确认；降级预案 I3'（训练时辅助监督，推理纯端到端）。
- **证伪**：仅在「能力受限」归因的失败段上，I3 才应有正增益；若增益均匀分布，说明归因错误或 I3 无针对性。

### I4 人手干预门控 + 自适应 chunk ★★★★（维持）

### I10 任务续航计 + 失败归因（新） ★★★★★
- **动机**：P11——长程任务失败是误差复利，但现有评测只有成败，没有「何时/为何不可恢复」；H1/H2 需要一个可测载体。
- **机制**：
  1. **离线续航画像**：成功示教 DTW 对齐 → 训练 progress/time-to-go 头 `c(s)` 与存活分类器 `g(s)`；对每条示教回放得到 `B_t` 曲线、漂移率 `λ`、PNR 分布；按任务聚合为续航曲线 `S(t)`。
  2. **在线燃油表**：每个 chunk 边界更新 `B̂_t = (b_t/b_0)·ĝ(s_t)`（只读缓存，零额外大模型调用）；`B̂` 跌破 β_lo 进入恢复态，高于 β_hi 保持执行（滞回抑制过纠）。
  3. **失败归因**：`t_fail` 前若 `B` 缓降 → 续航受限（路由 I10/I11/I12）；单 chunk 突降 → 能力受限（路由 I1/I2/I3/I5）。
- **与现有方案差异**：I5 是「检测到偏离就纠」的反应式恢复；I10 是**预测式预算管理**，并提供论文级诊断量。I8 度量「模块有没有用」，I10 度量「任务为什么死、死在哪」。
- **可行性**：中。全部用接口可见量（4 路 RGB + EE + 夹爪开口），无需深度/力觉；`c` 从成功示教自监督，`g` 用成功/近失败（I11 合成 + 真机 rollout）训练。
- **资源**：1×24GB GPU；离线计算为主；1–2 人周。
- **步骤**：①示教 DTW 对齐与 φ 定义；②训练 `c`、`g` 并校准；③留出集估计 `B_t` 与 `S(t)`；④**先证伪 H1**（AUROC vs 动作误差）；⑤在失败集上验证 H2 归因；⑥输出 32 任务续航曲线 + 归因表。
- **风险**：`B_t` 不可辨识（缓解：先用「进度落后 + 时间余量」两个可观测量做下限版本，再逐步加项）；`g` 校准漂移（按任务分层校准）；循环论证（训练/评估严格按任务留出）。
- **证伪**：见 H1/H2；另设「空模型」基线（只用剩余时间），若 `B` 不优于它则删除该项。

### I11 临界态恢复数据 + 预算标注（新） ★★★★
- **动机**：P12/P8——均匀扰动把样本浪费在「太简单」与「已不可恢复」两端；最 informative 的是**临界态**：`B_t` 接近 0 但仍可救。H3。
- **机制**：
  1. **边界选态**：用 I10 的 `B` 在示教/rollout 中选 `B_t ∈ [B_lo, B_hi]` 的状态（近 PNR 但未越过）。
  2. **合成恢复段**：对选中态施加受控扰动把 `B` 再压低一点，然后从最近的成功示教段**检索 + 拼接**出「后退-重对准-再抓」延续（复用 I5 底座；必要时 WMA 续写）。
  3. **预算标注 + 课程退火**：用 `g`/progress 验证段是否真的恢复到更高 `B`；给每段标 `ΔB`（消耗/回充）；训练时把目标 `B` 从高到低退火（先学容易救的，再学临界救的）。
  4. **物理可行过滤**：拼接处做 EE/夹爪连续性检查，拒绝跳变段。
- **与现有方案差异**：I5 v2 均匀扰动；I11 是**边界靶向 + 预算标注 + 课程**，把「造失败」变成「造可验证的临界纠正」。这是 active-learning 式的数据杠杆（PR5）。
- **可行性**：中-高；纯数据工程 + 轻量验证器。
- **资源**：1×24GB GPU；数据工程 2 人周；验证器 1 GPU 日/族。
- **步骤**：①3 任务（PlugCharger/ZipUp/PourOutMedicine）定位临界态；②采样 + 拼接 + 可行性过滤；③验证并标 `ΔB`；④LoRA 增量训练；⑤与 I5 v2 做匹配样本量 A/B（H3）。
- **风险**：边界估计误差（加安全边距，宁取可救侧）；拼接物理不可行（连续性过滤 + 人工抽检）；合成-真实失配（扰动幅度从 I1 考纲卡采样）。
- **证伪**：H3——同数据量下恢复成功率无提升即回退均匀扰动。

### I12 续航感知反馈预算（新） ★★★★
- **动机**：P11/P12——反馈带宽有限，应花在漂移最快处；chunk 长度 `T_a` 与恢复触发目前都靠默认/拍脑袋。H4/H5。
- **机制**：
  1. **漂移率估计**：从示教/rollout 回归开环执行下 `d_{t+Δ} ≈ d_t + λ_k Δ`，得每任务漂移率 `λ_k`。
  2. **`T_a` 选择**：开环漂移与反馈频率的经典权衡给出 `T_a* ≈ sqrt(2 ε_max / λ_k)`（`ε_max` 为可容忍偏差）；若 `T_a` 只能全局固定，则做**任务组合优化** `max_{T_a} Σ_k w_k E_k(T_a)`（`w_k` 按长程/续航受限占比加权），而非按平均精度选。
  3. **预算门控恢复**：chunk 边界（新观测到达时）用滞回：`B̂<β_lo` → 恢复；`B̂>β_hi` → 继续；中间 → 重查询。高预算时**主动不纠**（PR7）。
  4. **底座再定位（可选/高风险）**：F20 显示底座平移几乎未用；若能把「后退/侧移」纳入恢复动作且经真机验证，可扩大可存活集，否则不做（分布外风险）。
- **与现有方案差异**：把 chunk 长度从「调参」变成「预算分配/组合优化」；把恢复触发从阈值启发式变成带滞回的预算规则。
- **可行性**：中-高；需 `T_a` 可配（待确认）；小 `T_a` 依赖 I6 双率。
- **资源**：serving 1 人 + 离线估计；低成本。
- **步骤**：①估计 `λ_k`；②`T_a` 候选表；③组合优化；④滞回门控；⑤L0 回放验证过纠率 + L2 单任务。
- **风险**：`T_a` 被握手固定为全局（退化为组合优化）；小 `T_a` 触发延迟门禁（双率兜底）；频繁切换技能导致抖动（滞回 + 最小驻留）。
- **证伪**：H4/H5——若无增益或过纠率不降，回退默认 `T_a` + always-recover。

### I13 服务续航看门狗（新） ★★★
- **动机**：P13——评测是长跑；后段任务的系统性退化会被平均分放大，且最容易被忽视。
- **机制**：soak-test governor 监控 p99 延迟、GPU 温度/利用率、显存高水位、每端口错误率、动作统计漂移；预测退化并优雅降级（fp8→INT8、关双率、重启 worker 且 episode 状态隔离）；定期 canary episode 校准。
- **与现有方案差异**：多数队伍只优化单步延迟；本点把**长时可靠性**当一等公民，与「续航」主题一致。
- **可行性/资源**：高；低成本。
- **步骤**：①埋点；②320 集 soak test；③governor 与降级策略；④canary。
- **风险**：评测端逐集隔离会削弱效应（先做探针确认）；过度工程（只保留能显著降方差的策略）。
- **证伪**：H6——若退化与后段成功率无相关，则 I13 仅保留基础健康探针。

### 2.1 续航计与 PNR（I10）

```python
def recovery_budget(state, progress_head, viability, T_max, t, b0):
    c = progress_head(state)                 # 期望剩余步数（成功示教回归）
    b = (T_max - t) - c                      # 时间余量
    g = viability(state)                     # P(success | state)，已校准
    B = (b / max(b0, 1e-6)) * g              # 归一化恢复预算；B<=0 即 PNR
    return B, b, g

def attribute_failure(B_hist, chunk_len, slow_drop=0.05, jump=0.25):
    # B_hist: 每个 chunk 边界的 B
    dB = [B_hist[i+1] - B_hist[i] for i in range(len(B_hist)-1)]
    if min(B_hist) > 0:            return "success"
    if max(dB) < -jump:            return "capability_limited"   # 单 chunk 突降
    if sum(1 for x in dB if x < 0) >= 2 and max(dB) > -jump:
        return "endurance_limited"                                # 缓降
    return "unclear"
```

```python
def act_at_chunk_boundary(obs, B_hat, beta_lo=0.15, beta_hi=0.55, state=None):
    if B_hat < beta_lo:
        state = "RECOVER"                      # 低预算：允许恢复
    elif B_hat > beta_hi:
        state = "CONTINUE"                     # 高预算：主动不纠（PR7）

    chunk = policy.propose(obs, mode=state)

def choose_Ta(lam, eps_max, weights, Ta_grid=(1,2,4,8,16)):
    # 若 per-task 可配：Ta_k* ~ sqrt(2*eps_max/lam_k)
    # 若全局固定：组合优化
    return max(Ta_grid, key=lambda Ta: sum(w*endurance(k, Ta) for k, w in weights.items()))
```
