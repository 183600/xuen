# 第 1 轮（灵感循环 v2：「隐私保护」×「商业模式」）—— 从「刷分策略」到「可运营策略」：隐私预算 × 推理经济学

> **本轮不推翻 v1（UIP-01~10），而是给它补上两个真实部署中无法回避、却未被榜单直接计分的维度。** v1 回答的是「如何在 `observation→action` API 权限内把成功率与步骤分刷高」；v2 追问：**当观测里有人、当推理有成本、当 N 台真机并发调用时，什么样的策略仍然成立？** 核心判断是：隐私与商业模式不是赛后的合规/商业计划，而是会改变最优架构的**选择压力**——它们与「迭代验证」结合后，恰好能把 v1 最大的隐患（无限重试）改造成可证明的预算分配问题。

---

## 0. 先给直觉解释

**隐私保护的直觉。** 评测发生在真实桌面环境，4 路相机（左右高位 + 左右腕部）会把房间、屏幕、人的脸和手一并拍进来；「人为干扰」本身就是官方泛化轴之一。把 4 路 480×640 原图长期留在远端服务里，等于把整个工作场景复制到选手机器上。但注意：**接口本身就给了两个隐私杠杆**——`obs_delta_indices` 的键决定「评测端传哪些观测」，`image_resize` 决定「传多清楚」。因此隐私在这里不是抽象伦理，而是可度量的**观测暴露面**：少请求、低分辨率、原始数据不落盘、上游只发低维统计。隐私做得好，同时也减少带宽与序列化开销，天然有利于延迟。

**商业模式的直觉。** 比赛要求选手暴露 N 个连续端口、由评测系统逐台连接；每步响应延迟及其波动、动作统计规律性都会被记录并用于**结果可信度**判定（README §6）。这本质上是一个**多租户在线推理服务**：价值 = 成功率 + 步骤分，成本 = 每步延迟 / 算力 / 显存 / 多租户开销，可信度 = 延迟方差与动作规律性。于是「商业模式」可以严格操作化为：**在延迟与算力预算约束下最大化分数，并给出分数—成本的 Pareto 前沿**；而不是写一份商业计划书。

**两者合起来的直觉。** 隐私是「数据预算」，商业模式是「计算预算」。v1 的旗舰 UIP-01 用固定置信度门限 + 最大重试次数来防发散，但门限是拍的、重试是不计成本的。v2 把它换成：**用信息价值（VoI）决定「值不值得验证/重试」，用双预算（隐私暴露 + 延迟/算力）决定「还能不能验证/重试」**。这把一个启发式，变成了一个带约束的优化问题。

---

## 1. 再给严谨定义

### 1.1 观测暴露面（Privacy Exposure）

设提交声明的观测键集合为 \(K_\pi\)，键 \(k\) 的原生分辨率为 \(H_k\times W_k\)，实际传输分辨率为 \(r_k H_k\times r_k W_k\)，敏感度权重为 \(w_k\)（高位相机同时看到人/背景/屏幕，取 \(w_{\text{high}}=1.0\)；腕部相机主要看物体，取 \(w_{\text{wrist}}\approx0.3\)）。定义

\[
E(\pi)=\underbrace{\sum_{t}\sum_{k\in K_\pi} w_k\, r_k^2}_{\text{传输暴露}}
+\underbrace{E_{\text{disk}}}_{\text{落盘}}
+\underbrace{E_{\text{up}}}_{\text{向上游/第三方发送}},
\]

隐私目标：\(E_{\text{disk}}=0\)（原始观测不落盘）、\(E_{\text{up}}=0\)（原始帧不外发），并在分数损失不超过 \(\delta\) 的前提下最小化传输暴露：

\[
\min_{K_\pi,\{r_k\}} E(K_\pi,\{r_k\})\quad \text{s.t.}\quad S(K_\pi,\{r_k\})\ge S_0-\delta .
\]

**接口级限制（必须诚实说明）**：`metadata` 在握手时读取，`obs_delta_indices` 是**全局声明**而非逐 episode 可变；因此 PMOS 是一个**全局最小观测子集选择**问题，逐任务只能在已传输数据上做「忽略/脱敏」，不能减少已经发生的传输。这一点决定了 PMOS 必须靠离线消融求全局最优，而不是在线逐任务切换。

### 1.2 身份泄露（Identity Leakage）

设 \(\phi\) 是本地观测变换（人脸/屏幕遮挡、任务相关裁剪等），\(L_{\text{id}}(\phi)\) 为在人出现在画面内的留出集上，用一个现成人脸/人体重识别器对 \(\phi(x)\) 的身份识别准确率。隐私目标：

\[
L_{\text{id}}(\phi)\le \frac{1}{K}\;(=\text{随机猜测}),\qquad
I(\text{identity};\phi(x))\le \varepsilon_{\text{id}},
\]

同时要求**保留任务相关几何**：\(I(\text{object pose};\phi(x))\ge I(\text{object pose};x)-\delta_{\text{pose}}\)。即「去身份、不去可供性」。

### 1.3 效用、成本与可运营目标

效用沿用官方口径：\(S=\lambda_s\cdot\text{SuccessRate}+(1-\lambda_s)\cdot\text{StepScore}/100\)（两个口径都保留，不擅自合并）。成本定义为

\[
C(\pi)=\alpha\,\mathbb{E}[L]+\beta\,\mathbb{E}[F]+\gamma\,\mathrm{Var}(L)+\delta\,N+\eta\,E(\pi),
\]

其中 \(L\) 为每步延迟、\(F\) 为算力/FLOPs、\(N\) 为端口数、\(E\) 为观测暴露面（把隐私内部化为成本）。可运营目标：

\[
\max_{\pi}\; S(\pi)\quad\text{s.t.}\quad E_{\text{disk}}=0,\;L_{\text{id}}\le 1/K,\;\mathrm{P95}(L)\le L_{\max},\;\mathrm{Var}(L)\le \sigma^2,
\]

在所有可行解中再最小化 \(C\)，并报告 Pareto 前沿 \(\mathcal{P}=\{(S(\pi),C(\pi))\}\)。榜单只看 \(S\) 与可信度；部署看 \(C\)。两者都要报，避免「无限算力刷分」的伪胜利。

### 1.4 信息价值门控（VoI，本轮核心）

在子目标 \(g_i\) 处，令 \(p_i=\Pr(\text{当前子目标已失败}\mid\text{历史})\)，验证器敏感度/特异度为 \(se,sp\)，检测到失败后修复概率为 \(fix\)，修复后的期望剩余分数为 \(G_i\)，单次验证成本为 \(c\)（延迟+算力+暴露），误报导致的多余重规划伤害为 \(h\)。则**验证当且仅当**

\[
\boxed{\;p_i\,se\,fix\,G_i \;>\; c+(1-p_i)(1-sp)\,h\,G_i\;}
\]

推导见产物区 §2.1。与 v1 的固定 `conf_thr` 相比，这个门限会随「剩余分数 \(G_i\)、验证器质量、验证成本、误报伤害」自适应变化：**越到 episode 末尾、越不准、越贵，就越不该验证**。

### 1.5 预算分配（把重试变成背包）

一个 episode 内可用的验证次数受延迟预算 \(B\) 限制。把每个候选验证点 \(i\) 的 VoI 记为 \(v_i\)，则

\[
\max_{x\in\{0,1\}^M}\sum_i v_i x_i\quad\text{s.t.}\quad\sum_i c_i x_i\le B .
\]

若各点成本近似相同，按 \(v_i\) 取前 \(B\) 个即可；否则按 \(v_i/c_i\) 贪心（0/1 背包的 \(1/2\) 近似）。这直接替代 v1 的「固定最大重试次数」，把「重试」从拍脑袋变成**预算内的资源分配**。

### 1.6 隐私最小观测选择的求解

对每个候选键/分辨率组合做离线消融，估计边际分数 \(\Delta S_k\) 与边际暴露 \(\Delta E_k\)，按 \(\Delta S_k/\Delta E_k\) 贪心选择，直到再删就超过 \(\delta\)。若边际收益随暴露递减，则最优子集近似「嵌套」，贪心接近最优；否则用小型整数规划精确求解（32 任务 × 少量键，规模完全可控）。

## 3. 瓶颈假设（工作假设）

- **H1｜人因轴是隐私与鲁棒性的交集**：人为干扰既是泛化轴，也是隐私风险源（人脸/手入镜）。一个「检测人→去身份→把人的手当作动态障碍→安全暂停/绕行/恢复」的策略，可能同时提高该轴成功率与隐私指标。
- **H2｜验证是延迟/算力的主要成本项**：v1 的 VLM 逐步验证在 N 端口并发下会放大尾延迟。VoI 门控 + 预算分配应能在紧预算下优于「每步都验」与「固定门限」。
- **H3｜N 端口并发的尾延迟主要来自排队而非单次推理**：共享骨干时，准入控制与 per-port 隔离比单纯换更快模型更能压 P95 与方差。
- **H4｜全量 4 路高分辨率观测存在冗余**：腕部相机对精细操作关键，高位相机对场景/人因关键；可能存在一个「高位低分辨率 + 腕部原生」的全局子集，在分数损失很小的情况下显著降低暴露与带宽。
- **H5｜分数对重试不是单调的**：重试的边际收益递减、边际延迟与可信度代价递增；成本感知的停止/重试是 Pareto 改进，而非「牺牲分数换成本」。

## 4. 候选创新点（UIP-11~18）

围绕两个灵感词发散出 14 个草案，合并后收敛为 8 个（详见产物区 §0）。**旗舰是 PRISM**：它不是单点，而是把 UIP-11~15 合成一个「双预算提交管理器」——隐私最小观测 + 人因脱敏 + 信息价值门控验证 + 成本感知计算 + 多租户 SLA。选它作旗舰的理由：

1. **全部落在选手权限内**：只改 `get_action`/`metadata` 内部逻辑，不碰电机、ROS、执行层；
2. **直接使用接口杠杆**：观测选择、分辨率、chunk 长度、`reset()`、N 端口；
3. **正面回应 v1 的最大风险**：v1 的「无限重试」被 VoI + 预算取代，重试不再是无界发散；
4. **同时命中隐私与商业模式**：暴露面可度量、成本可度量、可信度可度量；
5. **与 v1 兼容**：UIP-01→UIP-14、UIP-02→UIP-17、UIP-07→UIP-18、UIP-08→UIP-16，是升级而非另起炉灶。

## 6. 本轮最大风险（一句话）

**最大风险是：隐私最小观测与成本感知停止会在「未见物体/人为干扰」等关键泛化轴上删掉真正有用的线索，导致榜单分数下降，而隐私与成本收益又不被官方直接计分——因此必须把这两类约束实现为「先离线消融、证明分数损失 ≤ δ 的 Pareto 改进」，而不是一上来就硬压。**

## 1. 旗舰深潜：PRISM

### 1.1 机制

PRISM 在 `get_action` 内部维护一个**每 episode 的预算状态机**，包含五层：

1. **观测层（PMOS）**：`metadata` 只声明全局最小观测键集合与分辨率（例如「左右高位 240×320 + 左右腕部原生」），从源头减少评测端传出的数据量与带宽。
2. **脱敏层（HAPI + DME）**：原始帧只进内存，不落盘、不外发；验证器与任何遥测只使用 `φ(obs)`（人脸/屏幕遮挡、任务相关裁剪）。检测到人时，额外输出「人存在/人手位置」低维状态，供策略做安全暂停/绕行/恢复。
3. **信念层（离线校准）**：用 PP-Harness 在公开数据上估计每个任务的子目标失败先验 \(p_i\)、验证器 \(se,sp\)、修复率 \(fix\)、误报伤害 \(h\)、验证成本 \(c\)。
4. **控制层（VoI-V + CAC）**：按 §2.1 的门限规划本 episode 的验证点集合（背包），执行 `k` 步后按需验证；根据剩余延迟预算动态调整 `k`、验证频率与是否提前结束（OBSI）。
5. **服务层（MTSB）**：N 端口共享骨干，per-port 历史/KV 隔离；用准入控制与批大小选择压 P95 与方差，避免并发下尾延迟异常（README §6 可信度）。

### 1.2 与 v1 的差异

| 维度 | v1（UIP-01） | PRISM（v2） |
|---|---|---|
| 验证触发 | 固定 `conf_thr` | 由 VoI 推导的自适应门限 |
| 重试 | 固定 `max_retry` | 预算内背包分配，边际收益递减即停 |
| 隐私 | 未考虑 | 暴露面 \(E\) 与身份泄露 \(L_{\text{id}}\) 作为硬约束 |
| 成本 | 未考虑 | 延迟/算力/多租户成本进入目标与约束 |
| 人因轴 | 作为普通干扰 | 隐私与鲁棒性的交集，专门处置 |
| 可信度 | 事后注意 | 服务层显式优化尾延迟与动作平滑 |

### 1.3 可行性、资源、落地步骤

- **可行性：高**。只改 `get_action`/`metadata`；`action_chunk_size`、`reset()`、N 端口都在接口内。验证器可用 Qwen2.5-VL-3B 级小模型或「几何规则 + 轻量分类头」混合；脱敏可用现成人脸/人体检测器。
- **资源**：公开 32 数据集做离线校准与回放；1 张推理卡可同时跑策略 + 小验证器；N 端口工程可用单进程多端点 + 共享 backbone。
- **步骤**：
  1. 建 PP-Harness：固定切分、基线复现、暴露审计、人脸/屏幕脱敏。
  2. 离线校准 \(p_i,se,sp,fix,h,c\)；做观测子集/分辨率消融，求 PMOS 的全局最优。
  3. 训练/接入验证器与脱敏器；实现 VoI 规划器与预算状态机。
  4. 实现 MTSB：N 端口、状态隔离、准入控制、尾延迟压测。
  5. 在回放上跑 E101–E108；通过门禁后再预约真机。
- **风险**：脱敏可能删掉任务线索；\(p_i\) 校准漂移；预算过紧导致验证不足；多端口并发下共享 backbone 的抖动。对应缓解见 §5。

## 2. 关键推导

### 2.1 VoI 门限（含误报伤害）

在子目标 \(g_i\)，令剩余可得分数为 \(G_i\)。不验证时：
\[
\mathbb{E}[R_{\text{no}}]=(1-p_i)G_i .
\]
验证（成本 \(c\)）时：真失败以 \(se\) 被检出、以 \(fix\) 修复；真正常以 \(1-sp\) 误报、以 \(h\) 造成伤害：
\[
\mathbb{E}[R_{\text{yes}}]=-c+p_i\,se\,fix\,G_i+(1-p_i)G_i\big[1-(1-sp)h\big].
\]
于是
\[
\mathrm{VoI}=\mathbb{E}[R_{\text{yes}}]-\mathbb{E}[R_{\text{no}}]
=-c+p_i\,se\,fix\,G_i-(1-p_i)(1-sp)h\,G_i .
\]
**验证当且仅当 \(\mathrm{VoI}>0\)**，即
\[
p_i\,se\,fix\,G_i>c+(1-p_i)(1-sp)h\,G_i .
\]
直观含义：验证器越准（\(se\uparrow,sp\uparrow\)）、修复越有效（\(fix\uparrow\)）、剩余分数越大（\(G_i\uparrow\)）、成本与误报伤害越小（\(c\downarrow,h\downarrow\)），越值得验证；**episode 末尾 \(G_i\to0\) 时自动停止验证**，天然避免 v1 的「尾段无效重试」。

### 2.2 预算分配：从「最大重试」到「背包」

一个 episode 的验证预算 \(B\)（由延迟 SLO 与端口并发折算）。令 \(v_i=\mathrm{VoI}_i\)，则
\[
\max_{x\in\{0,1\}^M}\sum_i v_i x_i\quad\text{s.t.}\quad\sum_i c_i x_i\le B .
\]
成本近似相等时取 \(v_i\) 前 \(B\) 个；否则按 \(v_i/c_i\) 贪心（0/1 背包 \(1/2\) 近似）。若需要严格最优，\(M\) 很小（每任务 3–6 个子目标），可直接枚举。

### 2.3 隐私—分数：带约束的观测选择

对每个候选键/分辨率 \(j\)，离线估计边际分数 \(\Delta S_j\) 与边际暴露 \(\Delta E_j\)。求解
\[
\min_{x\in\{0,1\}^n}\sum_j \Delta E_j x_j\quad\text{s.t.}\quad\sum_j \Delta S_j x_j\ge S_0-\delta .
\]
等价于最大化 \(S-\lambda E\)：对每个 \(\lambda\) 取 \(\Delta S_j-\lambda\Delta E_j>0\) 的键，扫描 \(\lambda\) 得到 Pareto 前沿。若边际收益随暴露递减，最优解近似嵌套，贪心即可。

### 2.4 多租户尾延迟

N 端口共享一个 backbone 时，设到达率 \(\lambda\)、单请求服务率 \(\mu\)、批大小 \(b\)。批处理提高吞吐但增加排队时延：
\[
L_{\text{P95}}\approx \underbrace{\frac{b-1}{2\mu}}_{\text{批内等待}}+\underbrace{\frac{\rho}{\mu(1-\rho)}}_{\text{排队}},\qquad \rho=\frac{\lambda}{N\mu}.
\]
可信度约束 \(\mathrm{P95}(L)\le L_{\max}\) 与 \(\mathrm{Var}(L)\le\sigma^2\) 决定最大 \(b\) 与是否准入；**不是模型越快越好，而是排队越稳越好**。

### 2.5 脱敏的不变量

理想的 \(\phi\) 应满足：对仅在身份上不同的 \(x,x'\)，\(\phi(x)=\phi(x')\)（身份不变性）；同时保留手/物体几何（可供性等变性）。操作化：用重识别器测 \(L_{\text{id}}\)，用任务验证器测可供性保持；两者同时达标才上线。

## 3. 伪代码

```python
class PRISM:
    def __init__(self, policy, verifier, masker, calib, cfg):
        self.policy, self.verifier, self.masker = policy, verifier, masker
        self.prior = calib["p"]          # per-subgoal failure prior (offline)
        self.se, self.sp = calib["se"], calib["sp"]
        self.fix, self.h = calib["fix"], calib["h"]
        self.c = cfg["verify_cost"]      # latency + compute + exposure, normalized
        self.B = cfg["verify_budget"]    # per-episode verification budget
        self.k = cfg["commit_steps"]
        self.conf_thr = cfg["conf_thr"]
        self.lang = None

    def reset(self):
        self.policy.reset()
        self.i = 0; self.used = 0; self.chunk = []
        self.plan = self._plan_voi(self.prior, self.B)

    def get_action(self, obs):
        o_pol = obs                          # in-memory only, never persisted
        o_ver = self.masker(obs)             # identity-stripping for verifier/telemetry
        if self._should_verify(o_ver):
            s, conf = self.verifier(o_ver, self.lang, self.i)
            self.used += 1
            if conf >= self.conf_thr and s == "fail":
                self.chunk = []              # force replan / retry
            elif conf >= self.conf_thr and s == "done":
                self.i += 1; self.chunk = []
        if not self.chunk:
            self.chunk = list(self.policy.get_action(o_pol)[: self.k])
        act = self.chunk.pop(0)
        return self._smooth(act)             # keep action statistics regular

    def _plan_voi(self, p, B):
        M = len(p)
        def G(i): return (M - i) * (100.0 / M)
        v = [p[i]*self.se*self.fix*G(i)
             - (self.c + (1-p[i])*(1-self.sp)*self.h*G(i)) for i in range(M)]
        order = sorted(range(M), key=lambda i: v[i], reverse=True)
        return set(i for i in order[:B] if v[i] > 0)

        return self.i in self.plan and self.used < self.B
```

## 5. 合成数值验证（已跑，非真机）

**目的**：在真机不可反复试的前提下，先验证「VoI 预算分配在紧预算下是否优于固定策略」。这是一个**合成校准实验**，不是真机结果。

**设定**：每 episode \(M=5\) 个子目标；失败先验 \(p\sim\mathrm{Beta}(2,5)\)；验证器 \(se=sp=0.85\)；修复率 \(fix=0.8\)；验证成本 \(c=10\)（归一化分数单位）；误报伤害 \(h=0.2\)；每步 10 ms、每次验证 30 ms；3000 个合成 episode。策略按先验规划前 \(B\) 个 VoI 最高的子目标验证（`voi`），与「从不验证」「前 \(B\) 个都验证」「按 \(p>0.2\) 选前 \(B\) 个」比较。

| 1 | 41.01 (0.18) | 51.17 (0.23) | 51.04 (0.29) | **53.90 (0.27)** |

## 7. 本轮最大风险（承接想法区 §6）

**最大风险是：隐私最小观测与成本感知停止会在「未见物体/人为干扰」等关键泛化轴上删掉真正有用的线索，导致榜单分数下降，而隐私与成本收益又不被官方直接计分——因此必须把这两类约束实现为「先离线消融、证明分数损失 ≤ δ 的 Pareto 改进」，而不是一上来就硬压。**
