# 第 10 轮 · 新灵感循环（本轮灵感：「轻量化结构」×「服务设计」）
> **基线**：第 9 轮 MetricVoiceGauge-ACMD（定义 493–539；引理 69–86；实验 E531–E570）。
> 本轮纪律：**承重路径 + 轻量服务蓝图 + 弱链/冗余对偶**。两个灵感分别治理 v9 的两笔新债：**结构债**（v9 的 MW 预算表是均匀拍定的，ID 只做"开关"而不做"截面优化"；缺信息负载路径、缺并联冗余、缺屈曲概念，故"轻量"只是休眠几个模块）与**可读性债**（v9 五级退化链是纯后台工程语义，从未声明"退化时人看到什么"；技术安全不等于服务连续）。

## 0. 直觉与动机

**灵感 1（轻量化结构 → 计算负载路径与截面优化）**
直觉：桁架不是每根杆都等粗——材料只沿**主负载路径**分布，并按应力配截面；细长杆受压会**屈曲**，失稳不是因为材料不够，而是因为缺少侧向约束。v9 主闭环正是一张载荷图：感知 → DA/SPR → AC → M₀。但 v9 的定义 535 契约表把模块当作彼此独立的杆件，按经验给 1ms / 0.2ms 的预算，既没有"哪条路径真正承重"的追踪，也没有"并联冗余"，更没有"屈曲"概念；而 v9 的抖动本质上就是**计算屈曲**：一个模块超时吞掉共享预算，诱发邻居超时级联。核心创新：**承重路径编译器（LPC）+ 结构健康监测器（SHM）**。LPC 离线把契约表编译成"服务-结构图"，标出安全负载与服务负载两条路径，计算细长度 λ_v 与柔度；SHM 在线只做廉价监测，预警屈曲先兆（队列深度侵蚀 slack）。关键约束：**轻量化不是删模块，而是删"不承重的截面"**。

**灵感 2（服务设计 → 蓝图、失点与恢复脚本）**
直觉：服务设计把系统分成前台的**接触点**与后台的**流程**，用蓝图标出**可见线**与**失点（fail point）**，并为每个失点预写**服务补救（service recovery）**脚本。v9 的五级退化链全是后台语言（K_eff、v^⊥、Level-1..5），却从未声明"退化发生时，人看到/听到什么"。这造成**静默失败**：系统在后台安全退化，前台却表现为"机器人突然变笨 / 卡住 / 沉默"，服务连续性被破坏。核心创新：**轻量服务蓝图引擎（SBE）**：每个退化级 ℓ 绑定一个声明式恢复脚本 ρ_ℓ（降速 + 解释 + 安全姿态 + 冷却回滚），并证明"无未脚本化前台状态"——技术退化必须在前台可读。

**灵感 3（两者合流 → 弱链-冗余对偶）**
直觉：结构可靠性与服务可靠性共享同一套**串并联代数**。串联（服务接触点）是**弱链**：Q_series = min_i Q_i，一个环节差，整体差；并联（安全冗余路径）是**至少一条可用**：A_parallel ≥ max_i a_i（保守下界）。v9 的"中立元"只给了一个抽象 ⊕；本轮把它特化为两个单子：串联 (min, +∞)、并联 (max, 0)——两者恰好互为 de Morgan 对偶。于是"轻量"有了严格目标：在满足串联弱链 SLA 与并联安全冗余 ≥2 的前提下最小化计算质量 Σm_v。**冗余只加在承重路径上，材料只给应力最大的杆。**

## 1. 研究问题

- **Q1（承重路径与冗余）**：如何从 v9 契约表自动编译出安全/服务双负载图，并在 ID 休眠、MW 超时等拓扑编辑下保证"无孤儿安全负载"（每条 M₀ 需求仍有 ≥2 条节点不相交连续路径）？
- **Q2（计算屈曲）**：细长度 λ_v=(D_v−Ŵ_v)/D_v 与突发到达的确定性界，能否给出"无超时级联"的充分条件，使 v9 抖动 p99 下降而不牺牲安全？
- **Q3（服务连续性）**：如何把每个技术退化级绑定到前台恢复脚本 ρ_ℓ，使"无静默失败"成为可检查不变式？人机协同（engagement）如何调制步速与恢复语用？
- **Q4（轻量最优）**：弱链-冗余对偶下的资源分配问题是否凸、其最优解能否在"新模块全中立"时严格退化为 v9 静态预算表（引理 91）？

## 2. 设计原则（在 P10–P12 基础上新增 P13–P15）

**P13 承重路径律（Load-Bearing Path, LBP）**
每个安全/服务需求必须可追溯到服务-结构图中的一条连续负载路径；任何拓扑编辑（休眠、超时、降级）仅在 (a) 安全负载存在并联替代路径（冗余 ≥2），或 (b) 所涉接触点有已声明恢复脚本 ρ 时被允许；禁止"孤儿负载"。

**P14 轻量服务蓝图律（Lightweight Service Blueprint, LSB）**
蓝图是一等公民：接触点、可见线、失点、恢复脚本显式声明；每个 v9 退化级 ℓ 映射到 ρ_ℓ；前台可观测状态必须在 τ_recover 内等于 ρ_ℓ 的声明输出，禁止静默失败；进入未脚本化前台状态即视为服务连续性违背。

**P15 弱链-冗余对偶律（Weakest-Link / Redundancy Duality, WLD）**
串联质量用 (min, +∞) 聚合（弱链），并联可用性用 (max, 0) 聚合（冗余）；中立元分别为 +∞ 与 0，与 MW 的 v^⊥ 注入一致。轻量分配在约束下最小化 Σ 计算质量，截面按"负载×关键度/刚度"分配，并对安全路径施加细长度下限 λ_min 以抑制计算屈曲。

## 3. 与基线的接口（如何退化）

- LPC 失效 ⇒ 不生成/不更新服务-结构图，沿用 v9 静态预算表与手写路径，等价 v9；
- SHM 失效 ⇒ λ_min 保护关闭，退化为 v9 的静态 WCET 检查；
- SBE 失效 ⇒ 前台不执行恢复脚本，退化为 v9"仅后台退化"（安全仍由 v9 引理保），等价 v9；
- LA 失效 ⇒ 预算回退 v9 默认表（定义 535），等价 v9；
- CPG 失效 ⇒ e≡1 无调制，步速与恢复语用取默认，等价 v9；
- 新模块全中立 ⇒ 完整 v9 MetricVoiceGauge-ACMD，再沿 v9 五级链退回 v8 / v7 / v6。

## 4. 预期贡献

1. **承重路径编译**：把 v9 契约表升格为可优化的服务-结构图，给出"无孤儿安全负载"的可检查条件（最大流 / Menger 判据）；
2. **计算屈曲理论**：细长度 + 突发界的无级联充分条件，把"抖动"从经验现象变成结构失稳问题；
3. **轻量服务蓝图**：退化链的"前台可读化"，把服务补救变成与技术退化同等重要的声明式设计；
4. **弱链-冗余对偶分配器**：串并联代数统一结构可靠性与服务可靠性，离线轻量化、在线仅 SHM；
5. **预算-安全-服务-自省四闭环**：分块释放算力反哺 DA/SPR/Cal，同时为恢复脚本留出前台时延预算；E571–E590 覆盖蓝图完备性、失点注入、屈曲、分配最优、人机协同与端到端。

## 5. 本轮最大风险

**一句话**：离线轻量化按"期望负载剖面"削冗余，而服务崩溃常来自剖面外的多故障并发（域偏移 × 超时 × 人走神）——被优化掉的并联路径恰是唯一能承重的，系统会以"技术安全、服务失语"的方式失败。

**新增定义 540（服务-结构图 ServiceStructureGraph）** 有向图 G=(V,E)，V=M∪T，M 为 v9 契约模块，T 为前台接触点；每条边 e=(u,v) 标注负载类 λ_e∈{S,Svc,B} 与时延 d_e。节点质量 m_v=Ŵ_v，刚度 k_v=1/Ŵ_v。若从 v 反向可达任一 M₀ 硬检查，则 v 位于安全负载路径；若从 v 前向可达任一接触点 t∈T，则位于服务负载路径。

**新增定义 541（承重路径与冗余度 LoadPath/Redundancy）** 需求 r 的承重路径 π 是 r 到其根（安全：M₀；服务：接触点）的一条连续路径，要求路径上所有节点均 active 且未超时。冗余度 r(π)=节点不相交承重路径数（Menger 最大流）。r(π)=0 称**孤儿负载**；P13 规定安全负载 r(π)≥2、服务负载 r(π)≥1 且有 ρ 脚本。

**新增定义 542（柔度 Compliance）** 记 delay_eff(r) 为需求 r 的最优可用路径时延（安全取并联最小、服务取串联链最大）。结构柔度 C(G)=Σ_r L_r·delay_eff(r)，其中 L_r=关键度×使用率。轻量目标即在约束下最小化质量 M(G)=Σ_v m_v。

**新增定义 543（细长度与计算屈曲 Slenderness/Buckling）** 细长度裕度 λ_v=(D_v−Ŵ_v)/D_v。若单周期突发 B_v 使实际工作量超过 D_v，则称模块 v **屈曲**；屈曲会通过共享预算传递，形成**超时级联**。安全路径要求 λ_v≥λ_min（默认 0.15）。SHM 以队列深度 q_v 与 EWMA-WCET 预测屈曲先兆。

**新增定义 544（服务蓝图 ServiceBlueprint）** B=(T,F,Bk,Sp,Φ_f,R,Vis)。T 为接触点集合；F/Bk/Sp 分别为前台动作、后台流程、支持流程；Φ_f 为失点集合；R={ρ_ℓ} 为恢复脚本族；Vis 为可见线（前台↔后台分界）。每个 t∈T 声明 SLA q_t=(ℓ_t,c_t,s_t,a_t)，服务质量的串联聚合为 Q(t)=min 归一化分量。

**新增定义 545（恢复脚本 RecoveryScript）** ρ_ℓ:(X,ℓ)→(前台动作序列, 后台模式)。约束三条：(i) 安全性——终态 ⊆ v9 Level-ℓ 的安全状态集；(ii) 时延——前台响应 ≤ τ_recover；(iii) 可读性——脚本含明确的原因/下一步说明（verbosity≥v_min）。ρ_ℓ 只读 ctx、不改变技术退化路径，故不引入新的安全分支。

**新增定义 546（服务连续性不变量 ServiceContinuity）** ∀t：技术级 ℓ(t) 与前台脚本 ρ(t) 的配对 (ℓ(t),ρ(t)) ∈ R，且前台可观测在 τ_recover 内等于 ρ_{ℓ(t)} 的声明输出，且 Q(t)≥q_min。任一时刻出现未脚本化前台状态即服务连续性违背（"静默失败"）。

**新增定义 547（串/并联单子 Series/Parallel Monoids）** 串联质量：(R∪{+∞}, ⊕_s=min, e_s=+∞)；并联可用性：([0,1], ⊕_p=max, e_p=0)。二者均为交换、结合、幂等单子，且经 x↦1−x 互为 de Morgan 对偶。**关键**：e_s=+∞ 与 e_p=0 正是 MW 在对应端口注入的 v^⊥；v9 的抽象 ⊕ 被特化为这两个单子，从而使"缺失模块"与"弱链/冗余"在同一代数中闭合。

**新增定义 548（人机协同门控 CoProductionGate）** 由 ER 输出的参与度 e(t)∈[0,1] 调制：K_eff(t) ← min(K_eff(t), K_cp(e))，K_cp(e)=max(1,⌊K_eff·(0.5+0.5e)⌋)；恢复语用 verbosity ← v_base+(1−e)·Δv；步速 pace ← pace_max·(0.5+0.5e)。e≡1 时退化为 v9（引理 91）。

## 3. 关键算法骨架

# IP-357 LoadPathCompiler：承重路径编译器（离线）
class LoadPathCompiler:
    def __init__(self, contracts, m0_checks, touchpoints, blueprint):
        self.contracts, self.m0, self.touch, self.bp = contracts, m0_checks, touchpoints, blueprint

    def build(self):
        G = DiGraph()
        for c in self.contracts:                       # 节点：模块与接触点
            G.add_node(c.name, mass=c.wcet_ms, deadline=c.deadline_ms)
        for c in self.contracts:                       # 边：In/Out 类型匹配
            for (u, v) in self._match_ports(c):
                G.add_edge(u, v, delay=self._edge_delay(u, v))
        self._label_load_classes(G)                    # 反向可达 M0 => S；前向可达 T => Svc
        return G

    def redundancy(self, req):
        # 节点不相交路径数 = 单位容量最大流（Menger）
        return self._max_node_disjoint_paths(req.src, req.dst)

    def admit_topology_edit(self, removed):
        """P13：返回 (是否允许, 证书)。MW 超时 ≡ 删除该节点（v9 引理 83）。"""
        G2 = self.G.copy(); G2.remove_node(removed)
        cert = {}
        for req in self.safety_reqs:
            r = self._max_node_disjoint_paths(req.src, req.dst, graph=G2)
            cert[req] = r
            if r < 2:                                   # 安全负载须始终有并联替代
                return False, cert
        for req in self.service_reqs:
            if not self.bp.has_script(req.touchpoint):  # 服务负载须有可读恢复脚本
                return False, cert
        return True, cert

    def _label_load_classes(self, G):
        for v in G.nodes:
            if nx.has_path(G, v, self.m0):
                G.nodes[v]['load_class'] = 'S'
            elif any(nx.has_path(G, v, t) for t in self.touch):
                G.nodes[v]['load_class'] = 'Svc'
            else:
                G.nodes[v]['load_class'] = 'B'


# IP-358 StructuralHealthMonitor：结构健康监测（在线 ≤0.1ms）
class StructuralHealthMonitor:
    def __init__(self, costs, lam_min=0.15, ewma=0.05):
        self.costs, self.lam_min, self.alpha = costs, lam_min, ewma
        self.wcet_hat, self.queue = defaultdict(float), defaultdict(float)

    def update(self, module, observed_wcet, queue_depth):
        m = module
        self.wcet_hat[m] = (1-self.alpha)*self.wcet_hat.get(m, observed_wcet) \
                           + self.alpha*observed_wcet
        self.queue[m] = queue_depth
        D, w = self.costs[m].deadline_ms, self.wcet_hat[m]
        lam = (D - w) / D
        if lam < self.lam_min or queue_depth > self.costs[m].backlog_limit:
            return BucklingAlert(module=m, lam=lam, queue=queue_depth,
                                 action=self._mitigate(m, lam))
        return None

    def _mitigate(self, m, lam):
        # 轻量结构的安全阀：先缩块长/降级低优先模块，再抬优先级，绝不扩容
        return {'K_eff': 1} if self.costs[m].load_class == 'S' \
               else {'defer': True, 'priority_boost': 1}

## 4. 推导

**引理 87（承重路径完整性与拓扑编辑可准入）** 若 LPC 对每个安全需求执行最大流判定、对每个服务需求检查 ρ 存在性，则任一被准入的拓扑编辑都保持"无孤儿负载"：安全需求 r(π)≥2，服务需求 r(π)≥1 且有脚本。证明：由 Menger 定理，节点不相交路径数等于单位节点容量最大流；删除节点按 v9 引理 83 等价于 MW 注入 v^⊥，故图编辑忠实反映运行时失效；准入判定逐需求检查流值，任何 r(π) 降为 0（安全 <2）即拒绝。∎

**引理 88（细长度守护抑制超时级联）** 设每模块突发 B_m，若 (i) λ_min>0 且 Ŵ_m+B_m ≤ (1−λ_min/2)D_m 对安全路径成立，(ii) Σ_m(Ŵ_m+B_m) ≤ B_dec，则 EDF 下无模块错过截止期，因而不产生超时级联。证明：EDF 的密度条件在膨胀工作量 Ŵ'_m=Ŵ_m+B_m 下仍满足 Σ_m Ŵ'_m/D_m ≤ Σ_m Ŵ'_m/B_dec ≤ 1（由 (ii)）；对任意区间 [t1,t2]，到达工作 ≤ Σ_m ⌈(t2−t1)/D_m⌉Ŵ'_m ≤ (t2−t1)+Σ_m Ŵ'_m，标准 EDF 需求界成立；故无首次超时，级联不存在。∎

**引理 89（蓝图-退化全映射与无静默失败）** 对 v9 的技术五级 ℓ=1..5，SBE 均声明 ρ_ℓ，且映射 R 为全函数；前台可观测在 τ_recover 内等于 ρ_ℓ 输出，故任何退化都不产生未脚本化前台状态。证明：有限枚举五级逐行验证（表 544/545），ρ_ℓ 的终态包含于 v9 Level-ℓ 安全集，脚本时延由 deadline_guard 约束 ≤τ_recover；定义 546 的不变量在每次 on_level 调用时断言，trace 提供可审计证据。∎

**引理 90（服务连续性保持与安全传递）** 若 ρ_ℓ 关于 ℓ 单调（越严重越保守）且终态安全集嵌套，则服务退化单调，且 v10 的任意外部行为仍在 v9 安全集内。证明：单调性使序列 ℓ(t) 的每次上升对应脚本保守度不减，不会"退化后反而更冒险"；终态嵌套 + 引理 89 的终态包含关系把安全性归约到 v9 引理 82–86；服务连续性由 Q(t)≥q_min 与 τ_recover 界共同保证。∎

**引理 91（轻量分配最优性与 v9 严格退化）** 分配 LP 在"新模块全中立"时约束退化为 v9 预算表，v9 表是可行解，故最优质量 M*≤M_v9；且当 LPC/SHM/SBE/CPG 全部注入中立元时，任意周期的可观测行为与 v9 逐位一致。证明：中立元分别为：LPC→不编辑图、SHM→λ_min=0、SBE→ρ=恒等（仅后台）、CPG→e≡1（定义 548 给出 K_cp=K_eff、verbosity=v_base），逐项代入 LP 与主闭环即得 v9 的静态预算与调用序列；LP 为凸（min/max 分段线性可切平面线性化），v9 表可行故 M*≤M_v9。∎

**引理 92（串并联对偶代数一致性）** 串联 (R∪{+∞},min,+∞) 与并联 ([0,1],max,0) 均为交换、结合、幂等单子，且 x↦1−x 将前者同构到后者；其单位元恰为 MW 在对应端口的 v^⊥，故弱链/冗余聚合与 v9 中立元退化在同一代数中闭合、可组合。证明：逐条验证单子公理（交换/结合/幂等/单位）；de Morgan 恒等式 1−min(a,b)=max(1−a,1−b) 给出同构；单位元代入定义 547 与定义 536 的 v^⊥ 表逐行核对一致。∎

**引理 93（协同门控不破坏安全）** e(t) 的调制只可能减小 K_eff、增大 verbosity 与降低步速，故 K_cp(e) ≤ K_eff；由 v9 引理 86，较小块长不增加每周期预算；故 CPG 不引入新的安全违背。证明：K_cp(e)=max(1,⌊K_eff(0.5+0.5e)⌋)≤K_eff（e≤1）；步速与 verbosity 不进入 M₀ 判据；因此所有指标路径仍由 v9 论证覆盖。∎
