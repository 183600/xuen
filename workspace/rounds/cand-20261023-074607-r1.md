## 一、上一轮留下的硬结论

v3.0 的结论很干净：在 held-out 50 上，NO 不是容量不够，而是**整数性间隙**。EPC 在根层的 slack 恰好为 0，57,236 个 OS 节点里 EPC 命中 0 次；精确商只合并了 4 个节点。也就是说，任何只检查「区间内总加工量是否超过 m·长度」的连续界，在根层都不可能判掉这些 NO。

工作区里还躺着一条未写入正式状态的线索：v4.1 的 MPC（machine-partition certificate）在 holdout 50 上把 45 例在根层判掉，只剩 5 例：idx 5、21、32、42、47。MPC 的做法是把任务划分到 m 条单机链上，保留链内优先序，但**丢弃跨机优先序**。这 5 例恰好就是跨机优先序造成差距的地方。MPC 是比 EPC 强的松弛，但它仍然没有把「谁必须在谁之前开始」这件事完整地写进证书。

于是本轮的问题变成：

> 能不能设计一个**保留优先序的流/割证书**，在根层把这 5 个 MPC 残例也判掉？

灵感词是「最大流最小割 / energy-efficient algorithm / 流算法」。我把它理解成：把时间轴看成能量预算，把每个任务看成一单位「开始时间流」，容量是每时刻 m 台机器，优先序是流在时间上的势差；证书就是这个流网络的**割**。

## 二、第一次尝试：分数优先序 LP，失败

最自然的流式松弛是时间索引 LP：

- 变量 x_{i,t} 表示任务 i 在 t 时刻被处理的量；
- 每个任务总加工量等于 p_i；
- 每时刻总处理量不超过 m；
- 优先序用**归一化累计量**表示：对每条边 i→j 和每个 t，
  (1/p_i)Σ_{u≤t} x_{i,u} ≥ (1/p_j)Σ_{u≤t} x_{j,u}。

这个 LP 是任何非抢占调度都满足的松弛：若 i 在 j 开始前完成，则在任何时刻，i 的完成比例都不小于 j 的完成比例。它也是文献里 preemptive precedence 松弛的标准写法。

我对 5 个残例在 h=OPT−1 上求解，结果**全部可行**。这并不意外：它允许任务在时间上被分数化，丢掉了「开始时间」这个真正的整数决策。换句话说，连续流只能证明「能量够」，不能证明「非抢占地排不下」。这条负结果和 v3.0 的 EPC 结论是一致的，但它把失败原因定位得更精确：不是容量界不够，而是变量选错了。

## 三、第二次尝试：start-time LP，根层关掉 3/5

把变量从「累计处理量」换成「开始时间指示」：

- z_{i,t} ∈ [0,1]，表示任务 i 在 t 时刻开始；
- Σ_t z_{i,t} = 1；
- 每时刻容量：Σ_i Σ_{s≤t<s+p_i} z_{i,s} ≤ m；
- 优先序：对每条边 i→j，
  Σ_t t·z_{i,t} + p_i ≤ Σ_t t·z_{j,t}。

最后一条就是「j 的期望开始时间不早于 i 的期望完成时间」。它仍然是非抢占调度的松弛：任何真实开始时间 s_i 取 z_{i,s_i}=1 都满足。但它比累计量 LP 强，因为它直接约束了开始时间这个整数对象。

在 5 个残例上，根层 LP 的结果是：

- idx 21、32、42：**不可行**，直接判 NO；
- idx 5、47：可行，需要继续分支。

这是本轮第一个正结果：同一个根层，EPC 和 MPC 都没关掉的 3 个例子，被一个多项式规模的 LP 关掉了。

## 四、分支：cut-guided start branching

对根层可行的 2 个例子，LP 解是分数的。分数的开始时间不是合法调度，但它给出了一个**割**：某个任务的开始质量跨在某个时间点两侧。取这个任务 i，令 mid 为其开始分布的中位数，分成两支：

- start_i ≤ mid：把所有 t>mid 的 z_{i,t} 上界设为 0；
- start_i > mid：把所有 t≤mid 的 z_{i,t} 上界设为 0。

任何整数开始时间都落在其中一支，所以这是合法的二分。两支都不可行时，原问题才判 NO。实测：

- idx 5：7 个 LP 节点；
- idx 47：19 个 LP 节点；
- 另外 idx 39 也是根层可行、3 个 LP 节点关掉。

合计 29 个 LP 求解，holdout 50 **全部在根层或根层分支内判 NO，OS 节点为 0**。

## 五、对偶：这就是割打包

start-time LP 的对偶不是又一个普通 LP，而是一个**割打包**：

- 每个时刻 t 一个价格 β_t ≥ 0，表示时间容量的割价；
- 每条优先序边 i→j 一个价格 γ_{ij} ≥ 0，表示跨机/跨任务延迟的割价；
- 每个任务一个自由变量 α_i，表示该任务所有可能开始时间里最便宜的那个价格。

对偶约束要求：对每个 (i,t)，任务 i 在 t 开始时占用的所有时间容量价格，加上优先序的势差价格，不超过 α_i。目标则是最大化「任务价格总和 − 容量价格总和 + 优先序延迟价值」。这正是一个**分数割打包**：β 是时间割，γ 是优先序割。

如果没有优先序行（γ=0），对偶退化成

  max Σ_i α_i − m Σ_t β_t
  s.t. α_i ≤ Σ_{t'∈[t,t+p_i)} β_{t'}，

这就是 Horn/EPC 的区间 min-cut；v3.0 的 EPC 正是它的一个特例。加上 γ 之后，割可以沿着优先序边「拐弯」，于是能表达「这组任务必须在那个时间窗之前/之后」这类非抢占信息。这是「最大流最小割」在本问题里的真正落点：不是一条普通流，而是一个带优先序势的时间割打包。

## 六、资格感知：机器割

holdout 是全资格（每个任务可上所有机器）。对异构资格，把变量细化为 z_{i,k,t}（任务 i 在机器 k 上于 t 开始），容量行变成每台机器每时刻 ≤1：

  Σ_i Σ_{s≤t<s+p_i} z_{i,k,s} ≤ 1，  ∀k,t。

对偶里就多出每台机器的价格 δ_{k,t}，即**机器割**。这样得到的 eligibility-aware LP：

- holdout 50：根层 47/50（与全资格 LP 相同）；
- large_het 8：根层 **8/8**（全资格 LP 只有 7/8）；
- 全 141 例：根层 138/141，剩余 3 例用 29 个 LP 节点分支关掉，总计 **141/141**。

全基准表：

## 七、消融：强度到底来自哪里

我在 5 个残例上做了四组消融（根层状态，0=可行，2=不可行）：

| 变体 | idx 5 | idx 21 | idx 32 | idx 42 | idx 47 |
|---|---:|---:|---:|---:|---:|
| 完整 start-time LP | 0 | 2 | 2 | 2 | 0 |
| 去掉优先序行 | 0 | 0 | 0 | 0 | 0 |
| 去掉容量行 | 0 | 0 | 0 | 0 | 0 |
| 分数优先序 LP（累计量） | 0 | 0 | 0 | 0 | 0 |

结论很清楚：

1. 只有容量行 → 退化成 EPC/preemptive，5/5 可行；
2. 只有优先序行 → 太弱，5/5 可行；
3. 两者同时存在，并且变量是**开始时间**而不是累计处理量，才产生 3/5 的根层不可行；
4. 剩余 2/5 的间隙是真正的整数性，需要分支，但只需 7 和 19 个 LP 节点。

正确性检查：在 T=OPT 上，5 个残例的根层 LP 全部可行；large_het 的 8 例在 T=OPT 上资格感知 LP 也全部可行。没有出现「在可行实例上误判 NO」的迹象。

## 八、代价：证书强，但墙钟不便宜

必须诚实地说：ECC 的 Python/scipy 原型在墙钟上不占优。

| 方法 | holdout 50 | OS 节点 | 墙钟 |
|---|---:|---:|---:|
| v3.0 WOS | 0/50 根层 | 37,364 | 0.1230 s |
| v4.1 MPC+WOS | 45/50 根层 | 2,176 | 0.0666 s（复跑） |
| v5.0 ECC | 47/50 根层 + 3 分支 | 0 | ~0.3–0.6 s（Python/scipy） |
| v5.0 ECC（141 例） | 138/141 根层 + 3 分支 | 0 | ~1.8 s（Python/scipy） |

ECC 的优势是**证书强度**和**节点数**：29 个 LP 节点 vs 2,176 个 OS 节点，且根层 LP 是多项式规模（n≤16、h≤63 时变量 ≤ 16·3·63）。劣势是每个 LP 的常数：scipy/HiGHS 每次 2–5 ms，而 WOS 节点是微秒级。要把强度变成端到端速度，需要把对偶割打包做成 C 实现的对偶单纯形/参数化 min-cut，或者只在 MPC 失败后的 5 个残例上调用 ECC（快级联），把 ECC 作为「最后一张证书」而不是第一道门。

快级联可以写成：

  ICC → MPC → ECC(root) → ECC(B&B) → WOS → PACE

在 holdout 上，45 例由 MPC 根层关掉，5 例由 ECC 关掉（3 根层 + 2 分支），OS 节点为 0；代价是 MPC 的 0.05 s 加上 ECC 的约 0.16 s。强级联则直接用 ECC 替代 MPC，牺牲墙钟换取 141/141 的根层/有界分支证书。

## 九、这一轮我真正学到的东西

不是「再加一个剪枝」，而是**换变量**。v3.0 的 EPC 和 v4.1 的 MPC 都在「处理量/机器划分」的空间里做割；它们都看不见非抢占的开始时间。start-time LP 把「开始时间」变成流，把优先序变成势差，于是同一个时间容量网络里同时出现了时间割、优先序割和机器割。分数优先序 LP 的失败说明：连续处理量不够，必须让割穿过「开始」这个离散事件。

## 十、一句话最大风险

最大风险是 ECC 的墙钟仍由通用 LP 求解器主导：根层证书虽把 141/141 全部判掉，但 Python/scipy 原型比 v4.1 的 OS 回退慢约 5–9×，若不能把对偶割打包做成 C 实现的割打包/对偶单纯形，这个强度优势在端到端指标上不会兑现。

## 0. 版本关系与本轮增量

本轮产物是 **v5.0 ECC（Energy-Cut Certificate）**，建立在两条既有基线上：

- **v3.0 WOS**：word 状态 OS 内核，负责兜底搜索；本轮不改内核。
- **v4.1 MPC**：机器划分根证书，45/50 holdout 根层判 NO；本轮把它保留为快级联的可选前置。

本轮增量只有一件事：在根层加入一个**保留优先序的 start-time LP 证书**，并在 LP 分数解上做**开始时间二分**。它不替代 WOS；它替代的是「MPC 失败后必须进 OS」这条路径。

推荐级联（快）：

  ICC → MPC → ECC(root) → ECC(B&B) → WOS → PACE

强级联（证书优先）：

  ICC → ECC(root) → ECC(B&B) → WOS → PACE

ECC 的适用范围：n ≤ 16、h ≤ 63、LP 规模在预算内；超出范围或节点预算耗尽时返回 UNKNOWN，交给 WOS/PACE，级联的 soundness 不受影响。

## 1. 符号

- n：任务数；m：机器数；p_i：任务 i 的加工时间。
- pred(i)、succ(i)：直接前驱/后继集合；elig(i)：任务 i 可用的机器集合。
- h：待判定的 makespan 上界（本轮的 NO 判定目标是 h = OPT−1）。
- est_i：由优先序得到的最早开始时间（head）。
- q_i：由优先序得到的最短尾部（tail）；d_i = h − q_i 是任务 i 的最晚完成时间。
- z_{i,t} ∈ [0,1]：任务 i 在 t 时刻开始的分数指示（全资格 LP）。
- z_{i,k,t} ∈ [0,1]：任务 i 在机器 k 上于 t 时刻开始的分数指示（资格感知 LP）。
- T：时间索引上界；本文取 T = h。

## 2. 形式定义

### 2.1 非抢占可行性

一个非抢占调度是一组整数开始时间 s_i，满足：

1. est_i ≤ s_i 且 s_i + p_i ≤ d_i（窗口/优先序）；
2. 对每个 t，至多 m 个任务满足 s_i ≤ t < s_i + p_i（容量）；
3. 对每条边 i→j，s_j ≥ s_i + p_i（优先序）。

全资格时机器身份无关；资格感知时还要求任务 i 被分配到 k ∈ elig(i)，且每台机器每时刻至多一个任务。

### 2.2 全资格 start-time LP

变量 z_{i,t}，t ∈ [est_i, h − q_i − p_i]。

    min 0
    s.t.  Σ_t z_{i,t} = 1                                  ∀i
          Σ_i Σ_{s≤t<s+p_i} z_{i,s} ≤ m                    ∀t
          Σ_t t·z_{i,t} + p_i ≤ Σ_t t·z_{j,t}              ∀(i→j)
          0 ≤ z_{i,t} ≤ 1

第一行是「每个任务恰好开始一次」；第二行是时间容量；第三行是「j 的期望开始不早于 i 的期望完成」。这是非抢占可行性的松弛：任何整数调度取 z_{i,s_i}=1 都满足。

### 2.3 资格感知 start-time LP

变量 z_{i,k,t}，k ∈ elig(i)，t ∈ [est_i, h − q_i − p_i]。

    min 0
    s.t.  Σ_{k∈elig(i)} Σ_t z_{i,k,t} = 1                  ∀i
          Σ_i Σ_{s≤t<s+p_i} z_{i,k,s} ≤ 1                  ∀k,t
          Σ_{k,t} t·z_{i,k,t} + p_i
              ≤ Σ_{k,t} t·z_{j,k,t}                        ∀(i→j)
          0 ≤ z_{i,k,t} ≤ 1

第二行是**每台机器**的容量割；这正是 EPC/HEC 的机器资格信息进入 LP 的位置。全资格 LP 是它的特例（elig(i) 全部相同，容量求和后除以 m）。

### 2.4 对偶：时间割 + 优先序割 + 机器割

以全资格 LP 为例，对偶变量：

- α_i（自由）：任务 i 的分配价格；
- β_t ≥ 0：时刻 t 的时间容量价格；
- γ_{ij} ≥ 0：优先序边 i→j 的延迟价格。

对偶：

    max  Σ_i α_i − m Σ_t β_t + Σ_{i→j} p_i γ_{ij}
    s.t. α_i ≤ Σ_{t'=t}^{t+p_i−1} β_{t'}
              + t·Σ_{j∈succ(i)} γ_{ij}
              − t·Σ_{h∈pred(i)} γ_{hi}          ∀(i,t)
         β_t ≥ 0, γ_{ij} ≥ 0, α_i free

解释：

- β_t 是「在 t 时刻占用一单位容量」的价格；正的 β_t 把割放在时间轴上。
- γ_{ij} 是「把 i→j 的优先序推迟一单位」的价格；正的 γ 让割沿着优先序边拐弯。
- α_i 是任务 i 所有可能开始时间里最便宜的那个价格；约束保证没有开始时间被低估。
- 目标最大化「任务价格总和 − 容量成本 + 优先序延迟价值」，是一个**分数割打包**。

若 γ=0，对偶退化为

    max Σ_i α_i − m Σ_t β_t
    s.t. α_i ≤ Σ_{t'∈[t,t+p_i)} β_{t'},

即 Horn/EPC 的区间 min-cut。因此 ECC 可以看作「带优先序势的 EPC 割」；v3.0 的 EPC 是它在 γ=0 时的特例。资格感知 LP 把 `m Σ_t β_t` 换成 `Σ_{k,t} δ_{k,t}`，并在每个 (i,k,t) 的约束里使用该机器的 δ；这就是机器割。

## 3. 算法

### 3.1 ECC 根层证书

输入 inst、h；输出 NO / YES / UNKNOWN。

1. 由 `heads_tails` 计算 est、q；构造 `StartLP`（全资格）或 `StartLPElig`（异构资格）。
2. 解 LP。
3. 若 LP 不可行：返回 NO（由 4.1 的松弛引理，原问题不可行）。
4. 若 LP 可行且所有 z 为整数：返回 YES，并把 z 翻译成开始时间（由 4.3）。
5. 否则进入 3.2 的分支。

### 3.2 cut-guided start branching

给定一个分数 LP 解 z：

1. 选一个分数质量最大的任务 i（实现里取 |z−1/2| 最小的变量所属的任务）。
2. 令 mid 为任务 i 的开始分布中位数：
   mid = min { t : Σ_{s≤t} z_{i,s} ≥ 1/2 }。
3. 左支（start_i ≤ mid）：对所有 t > mid，把 z_{i,t} 的上界设为 0。
4. 右支（start_i > mid）：对所有 t ≤ mid，把 z_{i,t} 的上界设为 0。
5. 递归求解两支；两支都返回 NO 时，本节点返回 NO；任一支返回 YES/UNKNOWN 时，本节点返回对应值。
6. 深度或 LP 节点数超过预算时返回 UNKNOWN。

分支是**开始时间割**：每一支都排除了任务 i 的一部分开始时间；两支覆盖所有整数开始时间。

### 3.3 级联伪代码

    function ECC(inst, h):
        est, q = heads_tails(inst)
        lp = StartLP(inst, h, est, q)          # 或 StartLPElig
        return search(lp, unit_bounds, 0)

    function search(lp, bounds, depth):
        if depth > D_max or nodes > N_max: return UNKNOWN
        res = lp.solve(bounds)
        if res == INFEASIBLE: return NO
        if res != OPTIMAL: return UNKNOWN
        z = res.x
        if integral(z): return YES(schedule(z))
        i = pick_job(z)
        mid = median_start(z, i)
        lo = bounds with z[i,t] = 0 for t > mid
        hi = bounds with z[i,t] = 0 for t <= mid
        a = search(lp, lo, depth+1)
        if a != NO: return a
        b = search(lp, hi, depth+1)
        if b != NO: return b
        return NO

    function decide(inst, h):
        if ICC(inst, h) == NO: return NO
        if MPC(inst, h) == NO: return NO
        if ECC_applicable(inst, h):
            v = ECC(inst, h)
            if v != UNKNOWN: return v
        return WOS_or_PACE(inst, h)

### 3.4 预算与回退

- 根层 LP 规模：变量 O(n·m·T)，约束 O(m·T + n + |E|)；n≤16、m≤3、T≤63 时变量 ≤ 3024。
- 分支预算：`N_max` 个 LP 节点、`D_max` 层；超预算返回 UNKNOWN。
- UNKNOWN 不改变级联的 soundness：后续 WOS/PACE 仍然给出最终判决。
- 若 LP 求解器不可用（原 stdlib-only 环境），ECC 自动禁用，级联退化为 v4.1。

## 4. 定理与证明

### 4.1 引理 1（松弛/soundness）

若存在满足 2.1 的非抢占调度，则 2.2/2.3 的 LP 可行。

**证明.** 全资格：令 z_{i,s_i}=1，其余为 0。分配行显然成立；容量行成立是因为任何时刻至多 m 个任务在执行；优先序行成立是因为 s_j ≥ s_i+p_i。资格感知：令 z_{i,k_i,s_i}=1，其中 k_i 是任务 i 在调度中使用的机器；每台机器每时刻至多一个任务，故容量行成立；其余同理。∎

**推论 1.** 若 LP 不可行，则不存在非抢占调度。这是 ECC 判 NO 的唯一依据。

### 4.2 引理 2（分支划分）

对任意任务 i 和整数 mid，任意整数开始时间 s_i 满足 s_i ≤ mid 或 s_i > mid；两支的边界集合互斥且覆盖所有整数开始时间。

**证明.** 整数三歧性。左支把所有 t>mid 的 z_{i,t} 置 0，因此只保留 s_i≤mid 的开始；右支把所有 t≤mid 的 z_{i,t} 置 0，因此只保留 s_i>mid 的开始。两支持有的整数开始时间集合不相交，并集为全部可能开始时间。∎

**推论 2.** 若左、右两支的 LP 都不可行，则不存在开始时间落在任一支的调度，即原问题不可行。

### 4.3 引理 3（整数叶）

若 LP 可行且所有 z 为整数，则 z 对应一个满足 2.1 的非抢占调度。

**证明.** 分配行 + 整数性 + 非负性 ⇒ 每个任务恰好有一个 z=1；令 s_i 为该 t（资格感知时同时得到机器 k_i）。容量行 ⇒ 每时刻至多 m 个任务在执行（资格感知时每台机器至多一个）。优先序行 ⇒ s_j ≥ s_i+p_i。窗口由变量范围保证。∎

### 4.4 定理 1（ECC 的 soundness）

ECC 返回 NO 仅当原问题不可行；返回 YES 仅当存在可行调度。

**证明.** 对分支树归纳。叶节点：LP 不可行由推论 1；整数可行由引理 3。内部节点：只有两支都返回 NO 才返回 NO，由推论 2；任一支返回 YES 时，该支的整数解就是原问题的调度。UNKNOWN 不产生判决。∎

### 4.5 定理 2（无预算时的完备性）

若 `N_max = D_max = ∞`，ECC 在有限步内终止，且对任意实例返回 YES 或 NO（不会返回 UNKNOWN）。

**证明.** 每次分支至少把所选任务的一个正质量开始时间置 0；变量数 N 有限，故分支树深度 ≤ N。树的每个节点解一个 LP；有限树 ⇒ 有限步终止。若原问题可行，由引理 1 根 LP 可行；沿任一可行调度的开始时间走分支，最终到达一个整数叶（或某个分支被剪掉前已覆盖该调度），由引理 3 返回 YES。若原问题不可行，所有叶 LP 不可行，归纳返回 NO。∎

**注.** 有预算时，ECC 可能返回 UNKNOWN；级联回退 WOS/PACE，整体仍是完备的（WOS/PACE 的完备性由 v3.0 的定理 2 保证）。

### 4.6 命题 1（对偶是割打包；EPC 是特例）

2.4 的对偶是一个分数割打包；当 γ=0 时退化为 Horn/EPC 的区间 min-cut。

**证明.** 对偶推导见 2.4。γ=0 时，对偶约束变为 α_i ≤ Σ_{t'∈[t,t+p_i)} β_{t'}；目标为 Σ α_i − mΣβ_t。取 β 为某个区间 [a,b) 的指示（乘以价格），就得到 EPC 的「区间内总加工量 − m·长度」对偶；最大化即找最紧的区间割。∎

**注.** 加上 γ 后，割可以沿优先序边从时间轴的一段「跳」到另一段；加上 δ 后，割可以按机器分裂。这三类割分别对应时间、优先序、资格，是本轮把「最大流最小割」落到非抢占调度上的具体形式。

### 4.7 命题 2（复杂度）

- 根层 LP：变量 O(n·m·T)，约束 O(m·T + n + |E|)；用多项式 LP（单纯形/内点）求解。
- 分支：最坏 O(2^N) 个 LP；本轮 141 例实测最多 19 个节点，总计 29 个。
- 在 n≤16、m≤3、T≤63 的范围内，LP 规模 ≤ 3024 变量，远小于 OS 的状态空间。

### 4.8 命题 3（预算下的终止）

`N_max`/`D_max` 有限时，ECC 必然在 O(N_max) 个 LP 内返回 NO/YES/UNKNOWN；不会无限递归。UNKNOWN 由级联回退处理。

## 5. 实验

### 5.1 设置

- 数据：141 例 NO 基准，h = OPT−1。
  - holdout 50（全资格，n 12–16，m=3）；
  - synth2_45（45）；
  - large_a 8、large_b 10、large_het 8；
  - hard3 12、deep 8。
- 实现：Python 3.12 + SciPy 1.18.1（HiGHS），单线程；`exp/v50/ecc.py`。
- 计时：单次 wall-clock；v4.1 的 0.0666 s 是本轮复跑，既有记录为 0.0524 s。
- 判定：根层 LP 不可行即 NO；根层可行则进入分支；分支预算 20,000 个 LP 节点（实测远低于此）。

### 5.2 主结果

| 数据集 | N | ECC 根层 NO | 需分支 | 分支 LP 节点 | 总计 |
|---|---:|---:|---:|---:|---:|
| holdout 50 | 50 | 47 | 3（5/39/47） | 7/3/19 = 29 | 50/50 |
| synth2_45 | 45 | 45 | 0 | 0 | 45/45 |
| large_a | 8 | 8 | 0 | 0 | 8/8 |
| large_b | 10 | 10 | 0 | 0 | 10/10 |
| large_het | 8 | 8（elig LP） | 0 | 0 | 8/8 |
| hard3 | 12 | 12 | 0 | 0 | 12/12 |
| deep | 8 | 8 | 0 | 0 | 8/8 |
| **总计** | **141** | **138** | **3** | **29** | **141/141** |

关键点：

- 根层 138/141，剩余 3 例全部是 holdout 的 idx 5/39/47；
- 分支只用了 29 个 LP 节点，最大单例 19 个；
- 全 141 例的 OS 节点为 0（ECC 单独完成判决）。

### 5.3 与 v3.0/v4.1 对比

| 方法 | holdout 根层 | holdout OS 节点 | holdout 墙钟 | 全 141 根层/总 |
|---|---:|---:|---:|---:|
| v3.0 WOS | 0/50 | 37,364 | 0.1230 s | 0/141（全部 OS） |
| v4.1 MPC+WOS | 45/50 | 2,176 | 0.0666 s | 45/50 + OS |
| v5.0 ECC | 47/50 | 0 | ~0.3–0.6 s（Python） | 138/141 + 3 分支 |
| v5.0 ECC（强级联） | 50/50 | 0 | ~0.3–0.6 s（Python） | 141/141 |

注意：v5.0 的墙钟是 Python/scipy 原型，不能与 v3.0/v4.1 的 C/word 内核直接比较；ECC 的节点数是 29 个 LP vs 2,176 个 OS 节点。ECC 的优势是**证书强度**，不是当前的常数。

### 5.4 消融（5 个 MPC 残例，根层状态：0=可行，2=不可行）

| 变体 | idx 5 | idx 21 | idx 32 | idx 42 | idx 47 |
|---|---:|---:|---:|---:|---:|
| 完整 start-time LP | 0 | 2 | 2 | 2 | 0 |
| 去掉优先序行（只留容量） | 0 | 0 | 0 | 0 | 0 |
| 去掉容量行（只留优先序） | 0 | 0 | 0 | 0 | 0 |
| 分数优先序 LP（累计量） | 0 | 0 | 0 | 0 | 0 |

解释：

- 只留容量 → EPC/preemptive 松弛，根层 5/5 可行，与 v3.0 的「EPC slack=0」一致；
- 只留优先序 → 太弱，5/5 可行；
- 分数优先序 LP（归一化累计量）→ 5/5 可行，说明「连续处理量」变量不够；
- start-time 变量 + 容量 + 优先序 → 3/5 根层不可行，剩余 2/5 只需 7/19 个 LP 节点。

### 5.5 正确性检查

- 在 T=OPT 上，holdout 5 个残例的根层 LP 全部可行（status 0），没有误判 NO。
- 在 T=OPT 上，large_het 8 例的资格感知 LP 全部可行。
- 消融中的「去掉优先序/容量」都返回可行，说明完整 LP 的 NO 不是由建模错误造成的。
- 分支只增加「开始时间 ≤ mid / > mid」的边界，不改变 LP 的其他行；由引理 2/3 保证 soundness。

### 5.6 代价

- Python/scipy 单次 LP 约 2–5 ms；holdout 50 的全资格根层 LP 约 0.23 s，资格感知版约 0.55 s；3 个分支约 0.11 s，总计约 0.3–0.66 s。
- 全 141 例根层约 1.68 s，加分支约 1.8 s。
- 对比：v4.1 holdout 0.0666 s；ECC 慢约 5–9×。但 ECC 的 LP 节点是 29，v4.1 的 OS 节点是 2,176；如果 C 实现对偶单纯形/参数化割打包能把单次 LP 降到 0.05 ms，ECC 的 29 个节点约 1.5 ms，量级上可以进入竞争区间。
- 快级联只在 MPC 失败的 5 例上调用 ECC：MPC 0.05 s + ECC 0.16 s ≈ 0.21 s（Python），仍慢于 v4.1 的 0.0666 s；这是当前实现的常数问题，不是算法节点数问题。

## 6. 风险与下一步

### 6.1 风险

1. **墙钟**：通用 LP 求解器的常数大；当前 Python/scipy 原型比 v4.1 慢约 5–9×。
2. **最坏情况**：分支树最坏指数；本轮最多 19 个节点，但 n/h 增大后可能退化。根层 LP 是多项式的，分支不是。
3. **根层限制**：ECC 目前只用根层的静态资格，不使用 OS 节点里的动态机器可用性剖面；它不是节点级证书。
4. **依赖**：SciPy 不在原始 stdlib-only 环境；最终实现需要 C 对偶单纯形或自写割打包求解器。
5. **对偶证书未显式提取**：当前只用 LP 的可行/不可行状态；下一步应提取 Farkas 对偶射线，输出可审计的 β/γ/δ 割。

### 6.2 下一步

1. 把 `StartLP` 的对偶做成 C 实现：时间割 + 优先序割 + 机器割的参数化/对偶单纯形；目标是单次 LP < 0.05 ms。
2. 用对偶射线选择分支变量（当前用分数质量中位数），减少 5/39/47 的节点数。
3. 做节点级 ECC：把 OS 的容量剖面 CP 作为 LP 的右侧，检查剩余子问题；这可能让 ECC 进入 WOS 的每个节点。
4. 在 n>16、h>63 上测 LP 规模与分支退化；在 YES 实例上测 UNKNOWN 率（当前只测了 NO 基准和 T=OPT 的根层可行性）。
5. 把快级联 `ICC → MPC → ECC → WOS` 接到 v4.1 的 `root_v41.py`，用同一套 141 例做端到端中位数计时。
