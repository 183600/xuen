# 第 16 轮（研究线累计；本轮灵感循环第 2 轮）· SWARM-VLA：把「群体智能」放进单模型推理期，用 K 个候选 + 四路视角 + 180s 时间预算做「先验证再执行」

> 检索/复核日期：**2026-11-02（UTC）**。赛事身份已再次核实：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮三个词是「真实世界泛化」「群体智能」「多模态交互」。**不推倒**第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO、第 13 轮 WAVE-SERVO、第 14 轮 VOI-MAP、第 15 轮 ZEST-VLA；SWARM-VLA 是 **VOI-MAP 与 ZEST 之间的动作选择层**：VOI-MAP 决定「做什么 / 看哪里 / 值不值得算」，SWARM 决定「这一步执行 K 个候选中的哪一个，还是先探一下」，ZEST 决定「执行后要不要信」。

## 0. 本轮先看到的三个硬事实

### 0.1 榜首 29.7%，但前四名在统计上打平

官方榜单 JSON（`leaderboard_data.json`，检索日期 2026-11-02）给出了 8 个通才模型、32 个任务、每个任务 10 次运行的聚合结果：

| 排名 | 模型 / 用户 | 平均成功率 | 步骤分 |
|---|---|---:|---:|
| 1 | MolmoAct2 / DexHacker | **29.7%** | 39.0 |
| 2 | WALL-OSS-0.5 / Generalist Robotics | 28.5% | 38.9 |
| 3 | DreamZero / World Model Lab | 27.9% | 37.9 |
| 4 | Spirit-v1.5 / VLAGO | 25.9% | 34.4 |
| 5 | DM0 / Embodied AI Institute | 23.5% | 31.7 |
| 6 | PI-0.5 / RoboReasoner | 22.8% | 30.6 |
| 7 | GigaBrain-0 / xembody | 22.6% | 29.5 |
| 8 | GR00T N1.5 / Humanoid Dynamics | 20.5% | 28.1 |

我原本想直接分析「第一名为什么强」，但先做了一次统计检查，结论很刺眼：

- 每个任务的成绩只有 **10 次运行**。在 p≈0.3 时，单任务二项标准误约 **14.5pp**；8 个模型在单任务上的成功率标准差只有 **2.5–9.5pp**，**小于噪声**。
- 第一名与第二名的差是 **1.2pp**（z≈0.33），与第四名的差是 **3.8pp**（z≈1.07）；**前四名在统计上不可分**。第一名与第八名的 9.2pp 才勉强显著（z≈2.70）。
- 32 个任务平均后，标准误约 **2.4pp**；所以「29.7% vs 28.5%」不是可靠的模型优劣，而是同一梯队内的噪声。
- 8 个模型的 task profile 两两相关平均只有 **0.10**（范围 −0.21～0.35）。这既可能是模型强项不同，也可能是单任务噪声太大；在 10 次/任务的条件下，**无法区分**。
- 用简单的 normal–normal 经验贝叶斯把每个 task 估计向模型均值收缩后，**每任务取最大值的「oracle」从 33.96% 缩到 29.70%**——正好等于最佳单模型的均值。换句话说，榜单上「换一个模型/换一个任务就能多拿 4pp」的想象，基本是噪声。

这不是说榜单没用；它说明**真正的杠杆不是 per-task 调参，而是提高 32 个任务的平均成功率、降低方差、以及利用评测协议里未被使用的资源**。

### 0.2 步骤分几乎就是成功率的仿射变换

我把 8×32=256 个模型-任务单元的 `avg_step_score` 对 `avg_success_rate` 做回归：

```text
step_score ≈ 0.093 + 1.337 × success_rate
r = 0.9977，最大绝对残差 1.303 分
```

也就是说，在当前榜单上，**步骤分几乎没有提供独立于成功率的信号**；排名实际上就是成功率排名。过程分只在极接近的成功率之间做 tie-break。策略含义：不要为了「过程分好看」而牺牲成功率；优先做能提高最终成功率的干预。

### 0.3 平均耗时 44s，上限 180s：评测协议留了一个巨大的时间预算

榜单 8 个模型的平均单任务耗时是 **43.7–45.2s**，而规则允许每个任务单次真机执行 **180s**。也就是说，头部模型平均只用了 **约 1/4 的时间预算**。而且耗时与成功率**没有相关性**（全局 r≈0.003）：慢并没有换来准。

这给了我本轮最重要的直觉：

> **在 30% 成功率的阶段，最便宜、最不依赖新模型、最符合规则的创新，可能不是「再训一个更大的 VLA」，而是「把 180s 里没用掉的时间，花在生成多个候选、验证、探测、重试上」。**

这与 LLM 的 test-time compute scaling 同构，但对象是动作块，不是 token。

## 1. 三个词怎么落到一个机制上

### 1.1 「群体智能」：先排除多机器人混模型，再落到单模型的虚拟群体

字面上的群体智能是 N 台机器人协同。但规则明确：**所有任务须基于同一模型完成，不得混合使用多个模型**；提交模板还要求每个端口 **独立 reset、状态隔离**。所以「N 台机器人各跑一个模型再投票」是违规的，跨端口共享原始轨迹也有 state isolation 风险。

我把「群体」重新定义为三层，全部合规或可控：

1. **单模型内的 K 个虚拟个体**：同一个冻结 checkpoint，用流匹配/扩散噪声、温度、光度增强、视角子集、历史偏移生成 K 个动作块。它们不是 K 个模型，而是同一个模型的 K 次采样。
2. **四路视角的群体**：头双目 + 左腕 + 右腕。每个视角是一个独立观测者；腕部在接近/抓取后提供头相机看不到的近距离接触证据。
3. **跨端口的聚合统计（可选）**：N 个端口只共享**聚合后的**校准分位数、失败签名、原语成功率，不共享原始观测/动作/ episode 状态。默认关闭，规则确认后再开。

这三层分别对应「候选多样性」「多模态互证」「跨机器人经验」，但都不违反单模型。

### 1.2 「多模态交互」：不是语音/手势，而是「头双目 + 腕部 + 本体 + 夹爪 + 语言属性」

API 的观测只有 4 路 RGB、关节/EE 状态、夹爪开合、语言指令；没有深度通道、没有力/触觉、没有音频。所以「多模态」在我这里不是再加一个模态，而是**把已有的模态用足**：

- **头双目**是校正过的立体对，可做几何深度/三角化；`state_d435` 还给了相机位姿。
- **双腕相机**是接触前后的近景，能看到夹爪与物体是否对齐、是否抓住、是否滑落。
- **EE pose + 正运动学**把腕部视角与头坐标系连起来，做跨视角几何一致性。
- **夹爪开合**是唯一的「触觉代理」：抓住物体时开合会停在物体宽度；空抓会闭合到很小。
- **语言**提供颜色/形状/数量/空间关系等可确定性解析的属性，用来做高置信度 veto。

这正好补上第 15 轮最大的盲区 **OOD-G**：如果 VLA 和语义地图共享同一个错误先验（例如都把透明杯子 ground 成旁边的盘子），残差会像 ID；但**腕部视角是独立像素证据**，可以在接近后看到「夹爪前方到底有没有那个物体」。它不能解决纯语义错误，但能把「一起错」拆成「至少有一个独立视角不同意」。

### 1.3 「真实世界泛化」：把 5 类泛化逐条映射到机制

规则说每个任务 10 次运行，5 类泛化各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。我的映射是：

| 泛化轴 | 主要失败机制 | SWARM 的对应机制 |
|---|---|---|
| 位置 | 目标偏移、抓取点/放置点变化 | K 候选 + 几何评分 + 小步重试 |
| 干扰物 | 语言 grounding 抓错物体 | 语言属性 veto + 跨视角目标一致性 |
| 桌面背景 | 视觉外观漂移 | 光度增强候选 + 共识（不改变动作坐标系） |
| 未见物品 | 外观/形状/材质变化 | 腕部近景重识别 + lift test + VLA 零样本 |
| 人为干扰 | 执行中人移动物体/遮挡 | 多视角运动检测 + `YIELD` 等待/重规划 |

其中**人为干扰**是数据集里没有、评测里却占 20% 的轴；这是我认为最值得单独下注的「真实世界泛化」缺口。

## 2. 主押注：SWARM-VLA

一句话：

> **第 15 轮用「动作-观测残差」决定执行后信不信；本轮用「K 个候选 + 四路视角 + 时间预算」决定执行前选哪个、要不要先探、要不要等人：把单模型的推理期从「一次前向」升级为「小规模、可验证、可回退的群体搜索」。**

四个组件：

1. **SWARM-K（群体候选）**：同一冻结模型生成 K=3–5 个动作块；用动作空间 medoid/共识选一个，而不是平均（平均会破坏接触精度）。
2. **XVG（跨视角几何验证）**：头双目 + 腕部 + EE pose + 夹爪开合 + 语言属性，做执行前 veto 和执行后 lift/contact 检查。
3. **LIFT（接触复检）**：抓取后抬升 1–2cm，比较夹爪开合、腕部图像、物体是否跟随；失败则重抓/换候选。
4. **TBY（时间预算 + 人干扰 yield）**：显式跟踪 180s 预算；人进入工作区时冻结/后退/等待，稳定后重新 grounding；预算内重试，接近上限则安全放弃。

### 2.1 与第 14/15 轮的分层

```text
L5  SWARM-VLA（本轮）      候选生成 → 多模态评分 → 选择/探测/放弃
L4  ZEST-VLA（第 15 轮）   执行后残差 → conformal/CUSUM 信任门
L3  VOI-MAP（第 14 轮）    语义地图 + 语言 grounding + 预算调度
L2  WAVE-SERVO（第 13 轮） TD-PC + 虚拟力 + 5 步块 + 限幅
L1  VLA server（唯一学习模型，冻结）
```

SWARM 只**选择** L1 的输出，不改变 L1 的权重；所有被选中的动作仍经过 L2 的安全限幅；ZEST 仍在执行后兜底。三层的职责不重叠：

- VOI-MAP：目标/预算（做什么）。
- SWARM：动作选择（怎么做、先不先试）。
- ZEST：执行后监控（做完信不信）。

### 2.2 为什么不是「多模型 ensemble」

- 规则禁止混合多个模型；SWARM 的 K 个候选全部来自**同一个 checkpoint**。
- 多模型 ensemble 需要 N 份权重/显存，且每个模型都要在未见任务上泛化；SWARM 只多花 K 次前向。
- 多模型平均动作会破坏接触阶段的精度；SWARM 选 medoid/最高分候选，保持一个合法动作块。
- 多模型无法解释「为什么选这个」；SWARM 的评分是可分解的（共识/几何/语言/安全），便于调试和预注册。

### 2.3 为什么不是「世界模型」

DreamZero/GigaBrain-0 已经证明世界模型/视频生成能提升泛化。但它们是**训练期**的重资产；本轮的主押注是**推理期、训练-free** 的补充：

- 如果队伍已经有一个 WAM，SWARM 可以直接用它作为候选生成器/前向预测器；如果没有，SWARM 仍可叠在任意 VLA 上。
- SWARM 不预测长视频，只做**短程几何一致性 + 接触验证**；它不需要一个 14B 视频模型就能给候选打分。
- 世界模型和 SWARM 是互补的：WAM 提供更好的候选，SWARM 决定选哪个。

## 3. 本轮合成实验：机制检查，不是真机证据

我写了一个纯 Python 的玩具模型 `exp/swarm_sim.py`，只回答一个问题：在「单模型每步只有 ~30% 成功、候选错误可能相关、重试可能把场景弄坏、人干扰占 20%、时间预算 60s」的设定下，K 候选 + 验证 + 重试 + yield 的**相对排序**是否成立。

默认单元（ρ_OOD-G=0.25，腕部可见性 0.5，人干扰 0.2，n=20,000）：

| 策略 | 成功率 | 平均耗时 | 成功/秒 | 探测/回合 |
|---|---:|---:|---:|---:|
| base（K=1，一次） | 29.4% | 10.0s | .0294 | 0.00 |
| retry（K=1，重试） | 32.4% | 17.1s | .0189 | 0.00 |
| kmedoid（K=5，共识） | 41.0% | 10.0s | .0410 | 0.00 |
| kmedoid_retry | 44.2% | 15.9s | .0278 | 0.00 |
| kverify（K=5，验证） | 43.4% | 11.1s | .0389 | 0.13 |
| kverify_retry | 48.2% | 17.6s | .0274 | 0.22 |
| **kverify_retry_yield** | **51.1%** | 18.4s | .0278 | 0.23 |

分解（相对 base）：K 共识 **+11.6pp**，验证 **+2.4pp**，重试 **+4.8pp**，人干扰 yield **+2.9pp**。在 ρ=0.5、腕部可见性 0.6、人干扰 0.2 时，base 21.3% → yield 40.2%（+18.9pp）；腕部可见性从 0 提到 0.9，yield 从 36.0% 提到 43.3%（+7.3pp）。这量化了「独立视角」对 OOD-G 的价值，也显示了边界：**共享错误越多，收益越小；腕部看不到，验证就退化成盲重试**。

**必须强调**：这是合成机制检查，绝对数值是乐观上界，不是真机收益；它的价值在于排序和边界，不在于「+21.7pp」这个数字。真正的证据要靠 G17–G21。

## 4. 可证伪假设

| 编号 | 假设 | 证伪条件 |
|---|---|---|
| H1 | K 候选共识在接触密集任务上比 K=1 提升 ≥5pp，时间 ≤2× | 3/5 任务无提升或时间爆炸 |
| H2 | 腕部跨视角验证对抓取/插入失败的 AUROC ≥0.7，假 veto ≤10% | AUROC <0.6 或假 veto >15% |
| H3 | 时间预算内重试 + 探测在难任务上提升 ≥8pp，p99 不超时 | 无提升或 timeout 增加 |
| H4 | 人干扰 yield 在 20% 干扰回合上提升 ≥10pp，碰撞不增 | 恢复率 <30% 或碰撞增加 |
| H5 | 收益随 OOD-G 比例上升而下降；腕部可见性是关键调节变量 | 收益与 OOD-G 无关（说明模型错了） |
| H6 | 官方 10 次/任务的 per-task 差异主要是噪声；A/B 必须 ≥30 次/任务或按任务聚合 | 用 10 次就宣称 per-task 显著 |

## 5. 剪枝：本轮明确不做

- 不做第二个学习检测/分割/语言/失败检测模型；XVG 只用确定性几何 + 经典 CV。
- 不做 test-time weight update / 在线微调；K 次前向不是学习。
- 不做跨端口原始轨迹共享；FLEET 只聚合统计，默认关闭。
- 不承诺解决纯语义 OOD-G；只增加一个独立视角的 veto。
- 不用水平翻转/大角度旋转做 TTA（会破坏动作坐标系）；只用光度增强、轻微裁剪/缩放并做动作反变换、视角子集、时间偏移。
- 不把 K 开到 10+；先 K=3–5，按 p99 和预算动态降级。
- 不追 per-task 榜单的 1–2pp 差异；那是 10 次运行的噪声。
- 不为了步骤分牺牲成功率；步骤分与成功率几乎共线。
- 不做全量 3D 重建；XVG 只用 2.5D 投影 + 局部几何。

## 6. 本轮最值得押注的一句话

**如果只能押一个点：SWARM-K + XVG——用同一冻结模型的 K 个候选动作，加上头双目/腕部的独立互证，把 180s 里没用掉的时间花在「先验证再执行」，而不是「执行后再后悔」；这是不改模型、不改规则、且直接利用榜单 44s/180s 时间空档的切入点。**

# 第 16 轮产物 · SWARM-VLA 技术报告

> 检索/复核日期：**2026-11-02（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是研究线累计第 16 轮、也是新一轮灵感循环第 2 轮「真实世界泛化 / 群体智能 / 多模态交互」的工程化产物。它在第 14 轮 **VOI-MAP** 和第 15 轮 **ZEST-VLA** 之间加一个**动作选择层**，不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO、第 13 轮 WAVE-SERVO。

## 0. 结论与边界

### 0.1 一句话结论

榜单头部 29.7%、前四名统计上打平、步骤分与成功率几乎共线、平均耗时 44s 而上限 180s。这四个事实共同说明：当前阶段最便宜的杠杆不是「再换一个更大的模型」，而是**把单模型的推理期从「一次前向」升级为「小规模、可验证、可回退的群体搜索」**。SWARM-VLA 用同一个冻结 checkpoint 生成 K 个动作候选，用头双目/双腕/EE pose/夹爪/语言属性做多模态互证，用 180s 里尚未使用的时间做探测、重试和人干扰 yield；它不训练第二个模型、不做 test-time weight update、不混合模型，因此符合单模型赛道的基本约束。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方页面、榜单 JSON、提交模板、数据集元数据直接核实 | 32 任务、8 模型、29.7% 榜首、10 次/任务、5 类泛化、180s、33,276 eps、4 相机、无 depth/force |
| B | 本轮在榜单/公式/合成实验上做的分析，可复现 | 二项噪声、经验贝叶斯 oracle、步骤分回归、`exp/swarm_sim.py` |
| C | 设计假设，需 G17–G22 验证 | 真实桌面候选多样性、腕部 veto 的 AUROC、人干扰恢复率、K× 延迟 |
| U | 未核验，不得进入论证链 | 规则手册未公开的后半部分、N 的精确值、每次 API 调用的硬超时、外部数据/测试时自适应条款 |

### 0.3 本轮不做什么

- 不训练第二个检测/分割/语言/失败检测模型；XVG 只用确定性几何 + 经典 CV。
- 不做 test-time weight update；K 次前向不是学习。
- 不做跨端口原始轨迹共享；FLEET 只聚合统计，默认关闭。
- 不承诺解决纯语义 OOD-G；只增加一个独立视角的 veto。
- 不用水平翻转/大角度旋转做 TTA；只用光度增强、轻微裁剪/缩放并做动作反变换、视角子集、时间偏移。
- 不把 K 开到 10+；先 K=3–5，按 p99 和预算动态降级。
- 不追 per-task 榜单的 1–2pp 差异；那是 10 次运行的噪声。
- 不为了步骤分牺牲成功率；步骤分与成功率几乎共线。

## 2. 榜单元分析：为什么「不到 30%」既是瓶颈也是机会

### 2.1 统计噪声：10 次/任务意味着什么

每个任务的成绩只有 10 次运行。对真实成功率 p，观测成功率的二项标准误是 `sqrt(p(1-p)/10)`；在 p≈0.2–0.3 时约 **12–14pp**。而 8 个模型在单任务上的成功率标准差只有 **2.5–9.5pp**（见 §2.2）。也就是说：

- 单任务的模型排名，大部分落在噪声里；
- 第一名与第二名的 1.2pp 差，z≈0.33；与第四名的 3.8pp 差，z≈1.07；**前四名统计上不可分**；
- 第一名与第八名的 9.2pp 差，z≈2.70，才勉强显著；
- 32 任务平均后的标准误约 `sqrt(0.19/320)≈2.4pp`；所以 29.7% vs 28.5% 不是可靠优劣。

| 比较 | 差值 | 近似 z | 读法 |
|---|---:|---:|---|
| 1 vs 2 | 1.2pp | 0.33 | 不可分 |
| 1 vs 3 | 1.8pp | 0.50 | 不可分 |
| 1 vs 4 | 3.8pp | 1.07 | 不可分 |
| 1 vs 5 | 6.2pp | 1.78 | 边缘 |
| 1 vs 8 | 9.2pp | 2.70 | 约 0.7% 单侧（未做多重校正） |

> 注：z 用两个 320 次运行的独立均值近似，未做多重比较校正；它只用于说明「别把 1–2pp 当结论」，不是官方显著性检验。

### 2.4 经验贝叶斯：per-task oracle 的 +4.3pp 基本是噪声

对每个模型 i、任务 j，令观测 `p_ij`（10 次），采样方差 `v_ij=p_ij(1-p_ij)/10`。假设真实 task 效应围绕模型均值 `μ_i` 有方差 `τ_i²`，用矩估计 `τ_i²=max(0, Var_j(p_ij) - mean_j(v_ij))`，再做 normal–normal 收缩：

```text
θ̂_ij = μ_i + (1 - v_ij/(τ_i²+v_ij)) (p_ij - μ_i)
```

结果：

- 观测的「每任务取最大模型」oracle 平均 = **33.96%**；
- 收缩后的 oracle 平均 = **29.70%**；
- 最佳单模型 = **29.70%**。

也就是说，在 10 次/任务的噪声水平下，**per-task 选模型的 +4.3pp 优势不能被数据支持**；它和最佳单模型的平均是同一水平。这个结论对策略很关键：不要把工程预算花在「给每个任务挑一个模型/模式」上，除非你能把每个任务的样本量提高到 ≥30–50 次。

### 2.5 步骤分与成功率几乎共线

对 256 个模型-任务单元回归：

```text
avg_step_score = 0.093 + 1.337 × avg_success_rate
r = 0.9977，max |residual| = 1.303
```

结论：**步骤分在当前榜单上没有独立于成功率的可用信号**；排名就是成功率排名，过程分只在极接近的成功率之间 tie-break。不要为了「过程分」牺牲成功率；也不要假设「过程分高 = 部分完成度高」在跨模型比较中成立。

### 2.6 时间预算：44s / 180s

8 个模型的平均耗时 43.7–45.2s；耗时与成功率的全局相关 r≈0.003（模型内相关也在 −0.20～+0.27 之间，符号不一致）。这说明：

- 头部模型平均只用了约 **1/4** 的 180s 上限；
- 「慢」并没有自动换来「准」；
- 评测协议里存在一个**未被充分利用的时间预算**。

SWARM 的核心就是把这段时间用于**候选生成、跨视角验证、探测、重试、人干扰等待**。这不是「无脑慢」：每一秒都要通过 VOI（第 14 轮）比较「预期成功率增益 / 时间成本」，并设硬上限避免 timeout。

## 3. 头部方案的做法与瓶颈

### 3.1 MolmoAct2（Action Reasoning）

公开的 MolmoAct 是「Action Reasoning Model」：把观测和指令编码成 depth-aware perception tokens，生成可编辑的 mid-level 空间轨迹，再预测低层动作；强调空间推理、可解释性和 OOD 泛化。它的优势是**空间/几何关系**和**可 steer**；瓶颈是：

- mid-level plan 是开环的「计划」，执行中若物体被移动/遮挡，计划需要重新生成；
- 接触密集任务（插网线、开锁、拔网线）需要的是**毫米级对齐 + 接触反馈**，不是纯空间推理；
- 公开报告的强项是 SimplerEnv/LIBERO 和单/双臂任务进展，不等于 32 项真实桌面任务的接触精度。

### 3.2 WALL-OSS-0.5（4B flow-matching VLA）

4B VLA，3B VLM backbone + action 组件；20+ embodiments、>1M trajectories/epoch；离散动作预测 + 多模态预测 + 连续 flow matching 的梯度桥接 co-training。它的优势是**大规模跨 embodiment 预训练**和**flow matching 的连续动作接口**；瓶颈是：

- 4B 模型推理成本高，K 采样会放大延迟；
- 预训练分布与 32 项桌面任务不完全一致，仍需 fine-tune；
- 接触密集任务需要的是局部几何/力，而不是更大的语义先验。

### 3.3 DreamZero（World Action Model）

14B autoregressive video diffusion，联合预测未来视频与动作，7Hz 闭环；公开报告称相对 SOTA VLA 在新任务/新环境上 >2× 泛化，并支持跨 embodiment/人类视频迁移。它的优势是**物理动态/零样本运动泛化**；瓶颈是：

- 14B + 视频扩散，推理重；7Hz 对高频接触控制偏慢；
- 视频预测「看起来对」不等于「物理上对」，在透明/反光/接触滑移上可能自信地错；
- 它和 VLA 可能共享同一个错误先验（OOD-G），需要独立视角验证。

### 3.4 GigaBrain-0（World-model-generated data + RGBD + CoT）

用世界模型生成 video/real2real/human transfer/view transfer/sim2real 数据，RGBD 输入 + embodied Chain-of-Thought，强调外观/位置/视角泛化。它的优势是**数据侧的规模化泛化**；瓶颈是：

- 生成数据的接触物理可能不真实；
- API 没有 depth 通道，RGBD 模型需要用双目估计深度；
- 训练期重资产，不适合小团队快速迭代。

### 3.5 π0.5 / GR00T N1.5 / Spirit-v1.5 / DM0

- **π0.5**：异构任务 co-training + web 数据 + object detection + semantic subtask + 低层动作；开放世界长程操作强，接触精度仍弱。
- **GR00T N1.5**：双系统（VLM + diffusion transformer）+ 异构数据；适合慢思考+快控制，但 N1.5 的精确细节需以官方为准。
- **Spirit-v1.5 / DM0**：本轮未找到可核实的公开技术报告；只作为黑盒对照，不引用内部细节。

### 3.6 共同瓶颈

1. **接触密集任务**：插网线、开锁、拔网线、挂杯子、拉拉链、叠毛巾；需要对齐/力/滑移检测，而 API 没有力/触觉。
2. **5 类泛化**：背景/干扰物/未见物品/位置/人干扰；数据集主要是干净演示，人干扰完全缺失。
3. **一次前向、不回头**：大多数 VLA 输出一个 chunk 就执行；失败后没有「候选比较/探测/重试」的显式机制。
4. **推理延迟**：大模型（4B–14B）与 7Hz/实时控制之间存在矛盾；K 采样会放大。
5. **评测噪声**：10 次/任务使得 per-task 结论不可靠；团队容易 overfit 榜单噪声。

### 3.7 架构取舍：VLA / World Model / 混合

| 路线 | 优势 | 瓶颈 | 对本队的含义 |
|---|---|---|---|
| VLA（WALL-OSS / π0.5 / GR00T） | 语义 grounding 强、推理相对轻、flow matching 易采样 | 接触物理/长程动态弱；对未见运动泛化有限 | 小团队的首选底座；SWARM-K 直接叠 |
| WAM（DreamZero / GigaBrain 类） | 物理动态/零样本运动强；可预测候选后果 | 14B/视频扩散重；7Hz；训练成本高 | 若算力允许，作为底座或候选评分器；否则不要硬上 |
| 混合（VLA 提议 + WAM/几何验证） | 语义 + 物理互补；理论上限最高 | 推理期两个模型可能违反单模型；延迟/显存翻倍 | 只在「同一 checkpoint 内多任务头」或「WAM 仅训练期」时合规；推理期不要混两个模型 |
| 混合（VLA + 确定性几何） | 合规、便宜、可解释 | 几何只能验证，不能创造新技能 | 本轮主推：VLA 提议 + XVG 验证 |

结论：**底座选一个开源 VLA（优先 flow matching），SWARM 作为架构无关的推理层；WAM 是可选增强，不是必需。** 如果队伍已经有 WAM，SWARM 可以直接用它做候选生成/前向预测；如果没有，不要为了「架构先进」而硬训一个 14B 视频模型。

## 4. SWARM-VLA：机制

### 4.1 分层与接口

```text
L5  SWARM-VLA（本轮）
      K 候选生成 → 多模态评分 → 选择 / 探测 / 放弃
      + 时间预算 + 人干扰 yield + 可选 FLEET 聚合
L4  ZEST-VLA（第 15 轮）
      执行后残差 → conformal/CUSUM 信任门 → FALLBACK/HOLD
L3  VOI-MAP（第 14 轮）
      语义地图 + 语言 grounding + 预算调度
L2  WAVE-SERVO（第 13 轮）
      TD-PC + 虚拟力 + 5 步块 + 限幅
L1  VLA server（唯一学习模型，冻结）
      WALL-OSS / π0.5 / GR00T / 自训 VLA
```

- SWARM 只**选择** L1 的输出，不改变 L1 权重；
- 所有被选中的动作仍经过 L2 的安全限幅；
- ZEST 仍在执行后兜底；
- VOI-MAP 仍决定目标/预算，SWARM 在其动作集内做候选级决策。

### 4.2 候选生成

设冻结策略为 `π_θ`，观测 `o_t`（4 路图像、本体、夹爪、语言 `u`），动作块长度 H。SWARM 生成：

```math
\mathcal{C}_t = \{ A_t^{(k)} \}_{k=1}^{K}, \qquad
A_t^{(k)} = \pi_\theta\big(T_k(o_t), u; \xi_k\big)
```

其中：

- `ξ_k`：流匹配/扩散的初始噪声、温度、dropout（若模型支持）；对确定性 VLA，置空。
- `T_k`：**动作等变/不变**的测试时变换：
  - 光度：亮度、对比度、色温、gamma（不改变动作）；
  - 轻微裁剪/缩放：必须把动作反变换回原坐标系；只允许小范围（≤5% 像素）；
  - 视角子集：全 4 路 / 头双目 / 头+同侧腕；用于测量视角依赖；
  - 历史偏移：`obs_delta_indices` 的不同堆叠（若模型支持变长历史）；
  - 禁止：水平翻转、大角度旋转、透视变换（会破坏左右臂/EE 坐标系）。
- K 的默认值：3–5；按 p99 和预算动态降级到 1。

**动作距离**：对两个 chunk `A, B`，用归一化 DTW 或逐时刻 L2（关节/EE 各自按量程归一化）：

```math
d(A,B) = \frac{1}{H}\sum_{h=1}^{H} \big\| \tilde a_h - \tilde b_h \big\|_2
```

**medoid**：

```math
A^{\mathrm{med}} = \arg\min_{A\in\mathcal{C}_t} \sum_{B\in\mathcal{C}_t} d(A,B)
```

medoid 保证选出一个**真实候选**，而不是平均出来的、可能不可执行的「中间动作」。

### 4.3 多模态评分

对每个候选 `A` 计算五类分数：

```math
S(A) = w_c C(A) + w_g G(A) + w_v V(A) + w_p P(A) + w_s Q(A)
```

| 项 | 含义 | 计算 | 依赖 |
|---|---|---|---|
| `C(A)` | 共识 | `-mean_B d(A,B)`；medoid 最高 | 动作块 |
| `G(A)` | 跨视角几何 | 头双目三角化目标；FK 推 EE 轨迹；投影到腕部；检查可见性/对齐/碰撞 | 4 相机、EE pose、标定 |
| `V(A)` | 语言属性 | 解析颜色/形状/数量/空间关系；与目标区域颜色直方图/边缘/尺寸比较；高置信不匹配才 veto | 语言、图像、经典 CV |
| `P(A)` | 预测进度 | 用 commanded motion + 场景几何估计目标距离减少；或复用 VLA 的 value-like probe | 几何、可选 VLA 特征 |
| `Q(A)` | 安全 | 关节速度/加速度限幅、自碰撞、桌面碰撞、夹爪范围 | 本体、FK |

**跨视角几何（XVG）细节**：

1. 头双目：用校正后的立体对估计视差/深度；目标像素由语言 grounding 或 VLA 的 action 轨迹给出。
2. 目标 3D 点 `X` 投影到腕部相机：`x_w = π_w(T_w^{-1} X)`；`T_w` 由 EE pose + 腕部外参（离线标定）得到。
3. 检查 `x_w` 是否在腕部图像内、深度是否在合理范围、局部 patch 的颜色/边缘是否与头视角一致。
4. 抓取后：比较夹爪开合与目标宽度；检查腕部图像中物体是否仍在两指之间；抬升 1–2cm 看物体是否跟随。
5. 透明/反光：降低颜色项权重，保留边缘/视差/夹爪宽度；若所有证据都弱，输出 `UNSURE`，交给 probe 而不是强行 veto。

**语言属性（V(A)）**：只做确定性解析，例如：
- 颜色词（红/绿/蓝/黄）→ HSV 直方图；
- 形状词（杯/碗/瓶/盒/管）→ 边缘/长宽比/圆度；
- 数量/顺序（两个、三个、从右到左）→ 目标计数/排序；
- 空间关系（在…上/里/旁）→ 目标相对位置。
不在词典里的属性不 veto；避免把「未见物品」误杀。

### 4.4 选择 / 探测 / 放弃

设 `S* = max_A S(A)`，阈值 `τ_commit > τ_probe`：

```text
if S* >= τ_commit:
    执行 argmax_A S(A) 的前 5 步
elif S* >= τ_probe:
    执行 probe（LOOK / 小步接近 / 换视角重采）
else:
    YIELD/HOLD 或请求 VLA 重规划
```

- `τ_commit`、`τ_probe` 在 ID 校准集上按「假 commit 率 ≤ α」选取；不是拍脑袋。
- 若最高分候选与 medoid 不一致，优先 medoid（更安全），除非最高分候选的 `G`/`V` 显著更好。
- 若 K 个候选都通过但彼此差异很大（高共识距离），视为**高不确定性**，降级为 probe。
- probe 不是「再想一遍」：它是一个**动作**（小幅移动/换视角/轻触），目的是获取新信息，而不是重复同一前向。

### 4.5 时间预算与 VOI

策略从 `reset()` 开始跟踪 wall-clock（API 不直接给 elapsed time，但可以本地计时）。设剩余预算 `B_t`，动作成本：

| 动作 | 成本 | 说明 |
|---|---|---|
| 生成 K 候选 | `K c_π` | 主要是 VLA 前向 |
| 验证 | `K c_v` | CPU 几何/颜色/投影 |
| probe | `c_probe` | 小步移动/换视角 |
| 重试 | `c_retry` | 失败后重新抓/重新规划 |
| yield | `c_wait` | 等人离开/场景稳定 |
| 安全停止 | `c_reserve` | 预留，绝不挤占 |

调度沿用第 14 轮的边际收益/成本：

```math
a^\star = \arg\max_{a\in\mathcal{A}_{\mathrm{adm}}} \frac{\Delta \hat P_{\mathrm{succ}}(a)}{c_a}
\quad \text{s.t.}\quad c_a \le B_t - c_{\mathrm{reserve}}
```

硬规则：

- 任务总时长上限 180s；策略自设 `B_max`（建议 120–150s），留 30–60s 给安全停止/意外。
- 若 `B_t < c_reserve + c_probe`，不再 probe，直接安全停止或执行当前最优候选。
- K 动态：`K=5` 用于关键决策（抓取前/插入前）；`K=1` 用于自由空间移动/已确认的接触段。

### 4.6 人干扰 yield

检测（确定性、经典 CV，不引入第二个学习模型）：

1. 头双目帧差：大连通域 + 深度比桌面更近；
2. 肤色/手臂形状启发式（仅在帧差区域内）；
3. 目标物体位置突变（与上一帧的 grounding 比较）；
4. 夹爪/EE 受到异常外力（位置跟踪误差突增；无 F/T，用跟踪误差代理）。

响应：

```text
DETECT -> FREEZE (停止当前 chunk)
       -> RETRACT (后退 2–5cm，保持安全)
       -> WAIT (直到场景稳定 T_stable，或人离开)
       -> RE-GROUND (重新观测/更新语义地图)
       -> RESUME (从当前相位重新选候选)
```

- 若人持续存在且预算不足：安全停止/放弃，不硬闯。
- 误检代价是几秒等待；漏检代价可能是碰撞/失败，因此阈值偏保守。
- 只在 APPROACH/PRECONTACT/自由空间 yield；在 CONTACT 中优先 freeze + 微退，避免拉扯。

### 4.7 可选 FLEET：跨端口聚合统计

N 个端口共享一个模型（README 的 Approach 2 明确允许共享后端）。FLEET 只聚合：

- 每个任务/相位的候选分数量化（均值/方差/分位数）；
- probe/retry 的成功率；
- 失败签名（残差模式、接触阶段、物体属性）；
- 校准分位数（ZEST 的 `q_α`）按机器人/相机分组。

不共享：原始图像、原始动作、episode 状态、reset 历史。每个端口仍有独立的地图/候选/预算/CUSUM。默认关闭；只有在规则确认「聚合统计不违反 state isolation」后才开。

### 4.8 伪代码

```python
class SwarmPolicy:
    def __init__(self, vla, calib):
        self.vla = vla                  # frozen, single checkpoint
        self.calib = calib              # thresholds, extrinsics, language parser
        self.map = SemanticMap()        # round 14
        self.plan = None
        self.mode = "TRUST"             # TRUST / PROBE / YIELD / FALLBACK
        self.budget = Budget(T_max=150.0, reserve=30.0)
        self.phase = "APPROACH"

    def get_action(self, obs):
        self.map = update_map(self.map, obs, self.plan)
        self.phase = observe_phase(self.map, obs)
        self.budget.tick()

        if human_detected(obs, self.map):
            return self._yield(obs)

        K = self._choose_k()
        cands = self._generate(obs, K)
        scores = [self._score(A, obs) for A in cands]
        best = max(range(K), key=lambda i: scores[i])
        s_star = scores[best]

        if s_star >= self.calib.tau_commit:
            A = cands[best]
            self.plan = A
            return self._safe_chunk(A, obs)
        if s_star >= self.calib.tau_probe and self.budget.can_probe():
            return self._probe(obs)
        return self._hold_or_replan(obs)

    def _generate(self, obs, K):
        out = []
        for k in range(K):
            o_k = self._augment(obs, k)       # photometric / view subset / history
            A = self.vla.infer(o_k, obs["observation.language"], seed=k)
            out.append(self._inverse_augment(A, k))
        return out

    def _score(self, A, obs):
        C = -sum(action_distance(A, B) for B in self._last_cands) / max(1, len(self._last_cands))
        G = cross_view_geometry(A, obs, self.map, self.calib)
        V = language_attribute_score(A, obs, self.calib)
        P = predicted_progress(A, obs, self.map)
        Q = safety_score(A, obs)
        return (self.calib.w_c * C + self.calib.w_g * G +
                self.calib.w_v * V + self.calib.w_p * P + self.calib.w_s * Q)

    def _yield(self, obs):
        self.mode = "YIELD"
        return self._safe_retract_or_hold(obs)
```

### 4.9 与 ZEST / VOI-MAP 的接口

```text
INIT -> GROUND -> SWARM(TRUST) -> {COMMIT, PROBE, YIELD, FALLBACK}
                         |                 |
                         |                 +-> WAVE-SERVO
                         +-> ZEST 执行后监控 -> TRUST / FALLBACK / HOLD
```

- SWARM 的 `PROBE` 是 ZEST `LOOK` 的动作级版本：ZEST 的 LOOK 决定「看哪里」，SWARM 的 PROBE 决定「用哪个候选/先不先试」。
- SWARM 的 `YIELD` 是新增的安全模式；ZEST 的 `HOLD` 仍是最后兜底。
- SWARM 的候选评分可以复用 ZEST 的残差作为 `P(A)` 的一项（执行前用历史残差预测），但不再训练任何东西。

### 4.10 接口工程：N 端口、异步 K 采样、状态隔离

- **端口**：提交需暴露 N 个连续端口（8765…）；每个端口独立 `reset`/状态。推荐「一个共享推理后端 + N 个轻量端点」：端点只做 msgpack 解码/token 校验/请求转发，GPU 后端做 batching。
- **并发**：不同端口可能同时调用；K 个候选可在后端 batch 成一次前向（若模型/显存允许），或用一个有界队列 + 超时降级。不要让一个端口的 K 采样阻塞其他端口。
- **状态**：每个端口一个 `SwarmPolicy` 实例；共享的只有冻结权重和可选的聚合统计；不共享候选/地图/预算/CUSUM。
- **带宽**：`obs_delta_indices` 只声明模型真正需要的键；`image_resize` 对头相机可降到 240×320，腕部保留更高分辨率（接触细节）。不要把所有 4 路都传原始 480×640×多帧，除非模型确实需要。
- **动作块**：`action_chunk_size=5` 作为默认（与 CHUNK-SERVO 一致）；K 候选只执行被选中那条的前 5 步；其余丢弃。
- **超时**：每个 `get_action` 设内部 deadline；超过 deadline 就返回上一合法 chunk/安全 hold，绝不返回 NaN/错误形状。K 动态降级：预算紧/队列长时 K=1。
- **token**：`metadata.token` 和每次 `meta.token` 都要带；N 个端口用同一 token；握手失败要能快速重试。
- **日志**：每个端口记录 K、评分、选择、耗时、模式、yield/probe/retry；用于 G17–G22 和 FLEET 聚合。

这部分不是「模型创新」，但它决定 K 采样能不能在真实评测的延迟/并发约束下落地；很多「离线很好」的方案死在接口工程上。

## 5. 性质与合规

### 5.1 单模型

- 所有候选来自同一个 `π_θ` checkpoint；K 次前向不是 K 个模型。
- 若是 flow matching/diffusion，采样噪声是模型本身的一部分；若是确定性模型，`T_k` 是输入预处理，不是新模型。
- XVG 的几何/颜色/边缘/夹爪检查是确定性算法；没有学习权重。
- 语言属性解析是手写词典/规则；没有第二个语言模型。
- 若评审认为「在线更新阈值」也算学习，可冻结所有阈值（用校准集一次性选好），只保留确定性评分。

### 5.2 状态隔离

- 每个端口独立维护：语义地图、候选集、预算、模式、CUSUM、候选历史。
- FLEET 只聚合统计，不共享原始观测/动作/episode 状态；默认关闭。
- 不跨端口复用 `reset` 前的历史；每个端口 `reset()` 清空自己的状态。

### 5.3 安全

- 所有被选中的动作仍经过 WAVE-SERVO 的 TD-PC、虚拟力、相位阻抗、限幅。
- 候选评分包含 `Q(A)` 安全项；不安全的候选直接淘汰。
- `YIELD` 是 freeze + 微退 + 等待，不是新的执行通路。
- 预算硬上限 + 安全停止预留，避免 timeout 前的失控。
- 接触阶段不做大范围 probe/retry；只在 APPROACH/PRECONTACT/原语边界。

### 5.4 延迟与复杂度

| 模块 | 复杂度 | 备注 |
|---|---|---|
| K 候选生成 | `O(K · T_π)` | 主导项；T_π 是单次 VLA 前向 |
| 动作距离/medoid | `O(K² H d)` | K≤5，H≤30，d≤14；<1ms |
| 跨视角几何 | `O(P)` | P 是目标/点云点数；CPU |
| 语言属性 | `O(P)` | 颜色直方图/边缘；CPU |
| 安全评分 | `O(H d)` | <0.1ms |
| 预算/VOI | `O(1)` | 可忽略 |

总延迟 ≈ `K × T_π + <2ms`。K=5 时，若 T_π=200ms，约 1s/决策；若 T_π=1s，约 5s/决策。必须在真机上测 p99，并支持动态降 K。

### 5.5 OOD-G 边界（命题）

设 ID 下候选评分分布为 `P_ID`，OOD-G（VLA 与地图共享同一错误先验、且腕部也看不到差异）下为 `P_G`。若 `TV(P_ID, P_G) ≤ ε`，则任何只依赖评分的 veto 检测器满足：

```math
\mathrm{FPR} + \mathrm{FNR} \ge 1 - \epsilon
```

等价地，AUC ≤ `1/2 + ε/2`。这就是第 15 轮命题 7 的延续：**如果所有独立视角都同意一个错误目标，SWARM 无法检测**。XVG 的价值在于把「所有视角都错」变成「至少腕部/几何可能不同意」，但它不是万能。

### 5.6 重试收益的界（推导）

设单次尝试成功率 `p`，一次失败是「持续性失败」（同一错误模式，后续重试也失败）的概率为 `q`，最多 R 次尝试。则：

```math
P_{\mathrm{succ}}(R) = p \cdot \frac{1 - [(1-p)(1-q)]^R}{1 - (1-p)(1-q)}
```

读法：

- q 越大，重试越没用；q=1 时退化为 p；
- q 越小，重试越接近 `1-(1-p)^R`；
- XVG/probe 的作用不是「增加 R」，而是**降低 q**（打破持续错误模式）。
- 这解释了合成实验里「盲重试 +3pp，而 K 共识 + 验证 + 重试 +19pp」的排序：关键不是重试次数，而是**每次重试前是否获得了新信息**。

## 6. 可证伪假设

| 编号 | 假设 | 主/次 | 证伪条件 |
|---|---|---|---|
| H1 | K 候选共识在接触密集任务上比 K=1 提升 ≥5pp，时间 ≤2× | 主 | 3/5 任务无提升或时间爆炸 |
| H2 | 腕部跨视角验证对抓取/插入失败的 AUROC ≥0.7，假 veto ≤10% | 主 | AUROC <0.6 或假 veto >15% |
| H3 | 时间预算内重试 + 探测在难任务上提升 ≥8pp，p99 不超时 | 主 | 无提升或 timeout 增加 |
| H4 | 人干扰 yield 在 20% 干扰回合上提升 ≥10pp，碰撞不增 | 主 | 恢复率 <30% 或碰撞增加 |
| H5 | 收益随 OOD-G 比例上升而下降；腕部可见性是关键调节变量 | 主（边界） | 收益与 OOD-G 无关 |
| H6 | 官方 10 次/任务的 per-task 差异主要是噪声；A/B 必须 ≥30 次/任务或按任务聚合 | 主（统计） | 用 10 次就宣称 per-task 显著 |

## 7. 实验与门

### 7.1 合成实验（已跑，B 级）

脚本：`exp/swarm_sim.py`；结果：`exp/swarm_results.json`。这是**机制检查**，不是基准证据。

生成模型（声明，不拟合）：

- 每个 episode 有 `ρ_OOD-G` 概率是共享 grounding 错误（所有候选同错）；否则每个候选以 `p_good` 独立为好。
- 好候选动作聚集在 0，坏候选在随机偏移；medoid 是共识动作。
- 验证分数：好 ~ N(1,1)，坏 ~ N(0,1)；腕部以 `wrist_vis × wrist_se` 检测共享错误；probe 以 `probe_fix` 修复。
- 执行：好 `p_succ_good`，坏 `p_succ_bad`，共享 `p_succ_shared`；失败后以 `p_persist` 进入 stuck，`stuck_scale` 缩放后续成功。
- 人干扰 `human_rate`；yield 以 `yield_detect` 检测、`yield_recover` 恢复。
- 时间：attempt 8s、候选 0.4s、验证 0.1s、probe 3s、wait 4s；策略预算 60s（硬上限 180s）。
- 默认：`ρ=0.25, wrist_vis=0.5, human=0.2, K=5, n=20,000`。

**默认单元结果**：

| 策略 | 成功率 | 平均耗时 | 成功/秒 | 探测/回合 | 尝试/回合 |
|---|---:|---:|---:|---:|---:|
| base（K=1，一次） | 29.4% | 10.0s | .0294 | 0.00 | 1.00 |
| retry（K=1，重试） | 32.4% | 17.1s | .0189 | 0.00 | 1.71 |
| kmedoid（K=5，共识） | 41.0% | 10.0s | .0410 | 0.00 | 1.00 |
| kmedoid_retry | 44.2% | 15.9s | .0278 | 0.00 | 1.59 |
| kverify（K=5，验证） | 43.4% | 11.1s | .0389 | 0.13 | 1.00 |
| kverify_retry | 48.2% | 17.6s | .0274 | 0.22 | 1.57 |
| **kverify_retry_yield** | **51.1%** | 18.4s | .0278 | 0.23 | 1.54 |

**消融（相对 base）**：K 共识 **+11.6pp**；再加验证 **+2.4pp**；再加重试 **+4.8pp**；再加 yield **+2.9pp**。

**OOD-G 边界（ρ=0.25 / 0.5，人干扰 0.2）**：

| 设置 | base | kmedoid | kverify | kverify_retry | +yield |
|---|---:|---:|---:|---:|---:|
| ρ=.25, vis=0.0 | 28.4 | 40.1 | 42.7 | 46.0 | 49.8 |
| ρ=.25, vis=0.6 | 29.2 | 40.5 | 43.9 | 48.0 | 51.5 |
| ρ=.25, vis=0.9 | 29.5 | 39.5 | 42.9 | 49.6 | 52.7 |
| ρ=.50, vis=0.0 | 21.0 | 28.3 | 30.1 | 33.4 | 36.0 |
| ρ=.50, vis=0.6 | 21.3 | 28.9 | 32.6 | 37.9 | 40.2 |
| ρ=.50, vis=0.9 | 21.2 | 28.0 | 34.0 | 39.4 | 43.3 |

读法：

- K 共识是最大单项；但它依赖候选错误独立；ρ 越高收益越小。
- 验证的价值在 ρ 高时更明显（vis=0.9 vs 0.0：ρ=.5 时 43.3 vs 36.0，+7.3pp）。
- 盲重试在 ρ 高、persist 高时收益有限；**新信息**（probe/腕部）才是关键。
- 绝对数值是乐观上界，不是真机收益；G17–G21 才能决定。

**效度威胁**：

| 威胁 | 影响 | 下一轮怎么补 |
|---|---|---|
| 候选错误模型是声明的 | 可能高估 K 共识 | 在真实 VLA 上测候选多样性/相关性 |
| 验证 se/fp 是声明的 | 可能高估 XVG | 在数据集/真机上测 AUROC |
| 重试成本/持久性简化 | 可能高估 TBY | 真机测失败后的场景退化 |
| 人干扰是单次事件 | 低估复杂干扰 | 加入多次/持续/遮挡干扰 |
| 时间预算 60s | 与 180s 上限不同 | 用真机 p99 和 timeout 数据校准 |
| 无真机 | 不能证明接触安全 | G18/G20 真机 A/B |

### 7.2 离线候选分析

**目标**：在真实数据/真实 VLA 上测「K 候选是否有用、评分是否校准」。

- 数据：从 32 个数据集中抽 100–200 episodes（每任务 3–5 条），优先接触密集任务（PlugInEthernet、Unlock、HangCup、PlugCharger、ZipUp、FoldTowel）。
- 模型：WALL-OSS-0.5（flow matching，易采样）或 π0.5/GR00T（若可获取）；至少一个开源 VLA。
- 方法：对每个决策点生成 K=5 候选（flow 噪声 + 光度增强 + 视角子集）；计算：
  - 候选两两动作距离（多样性）；
  - medoid 与 ground-truth action 的误差；
  - 评分 `S(A)` 与 action error / episode success 的 AUROC；
  - 跨视角几何项对「抓空/抓错/插入失败」的 AUROC；
  - 候选相关性与 ρ 的估计。
- 通过：medoid 动作误差比单样本降低 ≥10%；评分 AUROC ≥0.7；XVG AUROC ≥0.7，假 veto ≤10%。

### 7.3 真机单任务 A/B

| 项 | 设计 |
|---|---|
| 任务 | PlugInEthernet、Unlock、HangCup、FoldTowel、RemovePinnedNote（覆盖插入/开锁/挂/变形/拉取） |
| 次数 | 每任务 30–50 次，配对：base vs SWARM；同初始条件、同模型。若资源有限，至少 30 次，只报告效应量+CI，不宣称 5pp 显著 |
| 主端点 | 成功率；次端点：时间、成功率/时间、碰撞、timeout、probe/retry 率、p99 |
| 统计 | 配对差值 + bootstrap 95% CI；预注册；不宣称 5 次就显著 |
| 门 | G18（效应量门，非显著性门）：≥3/5 任务 +5pp，平均 +8pp，时间 ≤120s，无安全违规；显著性用 32 任务聚合或 ≥50 次/任务 |
| 注意 | FoldTowel 是变形任务，XVG 的几何项弱；它用于验证「不误杀」而不是「零样本成功」 |

### 7.4 泛化轴测试

- 3 个任务 × 5 轴 × 5 次 = 75 次/任务；或单任务通道 ≥30 次/轴。
- 轴：位置、干扰物、背景、未见物品、人干扰。
- 通过：≥3/5 轴有正增益；干净条件不回归 >2pp。
- 注意：官方 10 次/任务的 per-task 结果太吵；研发阶段必须用更多样本。

### 7.5 人干扰专项

- 20 个 episode，脚本化干扰：手进入、移动目标、遮挡 1–2s、放下新物体。
- 指标：检测率、恢复率、碰撞、等待时间、误 yield。
- 通过：恢复率 ≥50%，碰撞不增，误 yield ≤10%。

## 8. 创新点清单（持续迭代）

> 排序：P1/P2 是主押注；P3/P4 是主押注的接触/时间组件；P5 可选且规则风险；P6 是训练侧补强；P7 是方法论。每点都给出动机、与现有方案的差异、技术可行性、所需资源、落地步骤、风险。

### P1 · SWARM-K：单模型 K 候选 + 动作空间共识（主）

- **动机**：单次前向的 VLA 在 30% 成功率上，错误有很大偶发成分；同一模型的不同采样/增强可能给出不同的合法动作。K 个候选可以把「独立错误」变成可投票的群体；medoid 保持一个真实可执行动作。
- **与现有方案的差异**：不是多模型 ensemble（规则禁止）；不是动作平均（会破坏接触精度）；不是简单的 test-time augmentation（TTA 通常只做图像分类/检测，这里是动作块 + 共识 + 多模态评分 + 时间预算）。
- **技术可行性**：flow matching/diffusion VLA 天然可采样（WALL-OSS、π0.5、GR00T）；确定性 VLA 用光度增强/视角子集；K=3–5；动作距离用 DTW/L2；medoid 是凸组合之外的合法候选。
- **所需资源**：K× 推理算力（单卡/多卡）；无需新数据；API 不变；需要校准集选阈值。
- **落地步骤**：1) 在开源 VLA 上实现 K 采样；2) 数据集上测候选多样性与 medoid 误差；3) 单任务真机 A/B；4) 接入 VOI 预算与 ZEST。
- **风险**：候选错误相关（OOD-G）时无收益；K× 延迟；增强导致动作分布偏移；需要按 p99 动态降 K。

### P2 · XVG：头双目 + 腕部的跨视角几何验证（主）

- **动机**：第 15 轮最大盲区是 OOD-G（VLA 和地图一起错）。腕部是独立像素证据；插入/抓取失败常可在腕部近景看到；API 没有深度/力，头双目 + 腕部是最接近「几何真值」的通道。
- **与现有方案的差异**：不是第二个学习检测器；用已知 EE pose + 离线标定 + 投影/可见性/颜色/边缘/夹爪宽度；只做 veto，不生成动作；不引入新权重。
- **技术可行性**：数据集有 4 相机、EE pose、D435 pose；头双目已校正；腕部外参可离线标定；CPU 可算；透明/反光时降权。
- **所需资源**：标定数据（一次性）；经典 CV；无 GPU；需要目标 grounding（来自 VLA/语言/地图）。
- **落地步骤**：1) 标定腕部外参；2) 实现目标三角化 + 投影 + 可见性；3) 在数据集的成功/失败片段上测 AUROC；4) 真机接入 veto/lift。
- **风险**：透明/反光/遮挡；外参误差；颜色启发式对未见物体弱；只能检测几何/属性，不检测纯语义；误 veto 会降低成功率。

### P3 · LIFT：接触感知的抬升/重抓（主押注的接触组件）

- **动机**：跨模型最难的 6 个任务几乎都是接触密集；没有力/触觉，夹爪开合 + 腕部图像是唯一接触证据；lift test 是抓取成功的经典 cheap test。
- **与现有方案的差异**：把接触当作传感模态；不是学习触觉模型；确定性 lift/regrasp 状态机；与 ZEST 的 edit/slip 信号互补。
- **技术可行性**：API 有夹爪开合、腕部图像、EE pose；Dex1 开合范围 5.5–0；抬升 1–2cm 安全；失败可重抓。
- **所需资源**：无新数据；简单 CV；真机调试；安全限幅。
- **落地步骤**：1) 抓取后抬升 1–2cm；2) 比较夹爪宽度/腕部图像/物体跟随；3) 失败重抓或换候选；4) 记录接触残差给 ZEST。
- **风险**：抬升可能扰动物体；重抓耗时；透明物体图像弱；需要力/位置安全限幅。

### P4 · TBY：时间预算 + 人干扰 yield（主押注的鲁棒性组件）

- **动机**：平均 44s vs 180s；20% 人干扰；盲重试可能超时/破坏场景；评测协议给了未使用的时间预算。
- **与现有方案的差异**：显式时间预算 + 人检测 + yield/recover + 重试；不是固定步数/固定超时；不是「无脑慢」，而是按 VOI 分配。
- **技术可行性**：策略可本地计时；API 有 4 路图像/本体；人检测用帧差 + 深度 + 肤色启发式；无需新模型。
- **所需资源**：状态机；日志；真机测试；无 GPU。
- **落地步骤**：1) 预算管理器；2) 人检测/稳定窗口；3) yield/recover；4) 重试策略；5) 真机测 p99/timeout。
- **风险**：超时；误检；人离开后场景变化；重试导致物体移位；接触阶段 yield 可能拉扯。

### P5 · FLEET：跨端口聚合失败图谱（可选，规则风险）

- **动机**：N 台机器人共享一个模型；跨端口聚合统计可以加速校准/失败先验；这是「群体智能」的字面版本。
- **与现有方案的差异**：不是混模型/共享原始轨迹；只聚合统计（分位数、失败签名、probe/retry 成功率）；状态隔离。
- **技术可行性**：README 的 Approach 2 允许共享后端；需要共享存储/同步；每个端口仍有独立状态。
- **所需资源**：后端；日志；隐私/合规审查；跨机器人分布差异分析。
- **落地步骤**：1) 定义聚合 schema；2) 只在安全/校准层使用；3) A/B；4) 规则确认后再开。
- **风险**：可能被认定为违反 state isolation/fairness；跨机器人分布差异；默认关闭。

### P6 · HDA：人干扰轴的训练侧增强（训练侧补强）

- **动机**：数据集没有人干扰，评测有 20%；这是最大的未覆盖轴；仅靠推理期 yield 只能恢复一部分。
- **与现有方案的差异**：针对「人干扰」这一特定轴合成数据；不是通用 world-model 数据生成；与 P4 的 yield 互补。
- **技术可行性**：2D 合成（真人手部视频 + 深度排序）或视频生成；fine-tune 开源 VLA；不需要从头训练。
- **所需资源**：GPU；手部视频/生成模型；训练数据；真机验证。
- **落地步骤**：1) 收集/合成人干扰片段；2) fine-tune；3) 与 yield 结合；4) 真机 20 回合测试。
- **风险**：sim-to-real；合成伪影；训练成本；单模型合规（训练辅助，不是推理第二模型）。

### P7 · STAT：噪声感知的评测协议（方法论）

- **动机**：10 次/任务的二项噪声 12–14pp；per-task 榜单差异不可靠；top4 统计打平；用 10 次做 A/B 会 overfit。
- **与现有方案的差异**：不是模型；是实验设计；用官方不计分的单任务通道跑 ≥30 次/轴；配对/分层/预注册；Wilson/贝叶斯区间。
- **技术可行性**：单任务通道不计分，可反复测试；远程 API 可自动化；需要真机时间。
- **所需资源**：真机时间；评测配额；日志/统计脚本。
- **落地步骤**：1) 建本地/远程 harness；2) 按 5 轴分层；3) 预注册端点；4) 用区间而非点估计决策。
- **风险**：评测资源有限；单任务通道与全量分布不同；过拟合测试集；需要主办方配额。

### 8.1 保留 / 剪枝

**保留**：FACT-VLA 的相位化 BC；GEO-RESIDUAL 的几何残差/编辑检测；CHUNK-SERVO 的 30/5 双频；WAVE-SERVO 的 TD-PC/限幅；VOI-MAP 的语义地图/预算；ZEST 的 conformal/CUSUM 信任门；单模型合规；预注册统计纪律。

**剪枝**：
- 不做第二个学习检测/分割/语言/失败检测模型；
- 不做 test-time weight update；
- 不做跨端口原始轨迹共享；
- 不承诺纯语义 OOD-G；
- 不用水平翻转/大角度旋转 TTA；
- 不把 K 开到 10+；
- 不追 per-task 1–2pp；
- 不为步骤分牺牲成功率；
- 不做全量 3D 重建。

## 9. 风险与失效模式

| 风险 | 影响 | 缓解 |
|---|---|---|
| **OOD-G 共享错误** | 所有候选/视角一起错，SWARM 无法检测 | 命题 5.5 明确边界；XVG 只增加独立视角；不承诺解决 |
| 候选错误高度相关 | K 共识无收益 | 用真实 VLA 测候选相关性；若 ρ 高，减少 K，转 XVG/probe |
| 腕部不可见/透明/反光 | XVG 误判/漏判 | 降权颜色项；用边缘/视差/夹爪宽度；输出 UNSURE |
| K× 延迟/timeout | 评测超时/失败 | 动态 K；异步/并行；缓存；硬预算；p99 门 |
| 人检测误报 | 任务被无谓中断 | 保守阈值；短等待；连续帧确认；只在安全阶段 yield |
| 重试破坏场景 | 物体移位/掉落 | 限次数；lift 失败先回原位；ZEST 残差判断 |
| 语言属性词典错 | 误 veto 未见物品 | 只在高置信时 veto；未见属性不 veto |
| 单模型解释争议 | 被判第二个模型 | 全部确定性；无学习权重；可冻结阈值；写清 C1/C2 |
| FLEET 规则风险 | 违反 state isolation | 默认关闭；只聚合统计；规则确认 |
| 评测噪声 | 把噪声当涨点 | ≥30 次/任务或按任务聚合；预注册；置信区间 |
| 引用污染 | 假文献支撑真结论 | 引用审计；U 级排除；榜单条目与论文分开 |

**已知失效模式**：

| 场景 | 会发生什么 | SWARM 行为 | 结果 |
|---|---|---|---|
| 透明杯子（OOD-G） | 头/地图/VLA 都把杯子 ground 成盘子；腕部也看不清 | 评分像 ID，不 veto | **自信抓错**；只能靠外部语义/触觉 |
| 未见物体颜色 | VLA 动作不匹配外观；腕部颜色/边缘可见 | 候选分低/属性 veto | probe/换候选；可能恢复 |
| 干扰物遮挡 | 头视角目标被挡；腕部接近后可见 | 跨视角不一致 | probe/换候选；可能恢复 |
| 人移动目标 | 执行中目标消失 | 帧差/深度检测到 | YIELD/等待/重定位；可能恢复 |
| 瞬态执行失败 | VLA 短暂不一致 | K 候选/验证发现 | 换候选/重试；可能恢复 |
| 传感器噪声尖峰 | 评分抖动 | 阈值/滞回/多帧确认 | 不误触发 |
