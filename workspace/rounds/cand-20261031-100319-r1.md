# 第 13 轮（新灵感循环第 1 轮） · BUDGET-GAIT：把指标体系做成影子价格，把步态规划做成站姿图，把续航能力做成 320 trials 的预算管理

> 复核日期：**2026-10-31（UTC）**。本轮在项目时间线上承接第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO；不推倒前作，而是在它们之上加一层「资源感知执行器」。A 级事实沿用 **2026-10-28** 的核对结果；本轮不新增未核实的外部声明，新增内容均为设计与推导（C 级）。

## 0. 先给结论：下一层瓶颈不是「动作有多聪明」，而是「这个动作值多少预算」

第 12 轮把反馈周期从 1 秒压到 167 毫秒，解决了「最后 3 厘米开环」的问题。但它默认了三件事：

1. 身体站姿是固定的；
2. 算力、热和网络是免费的；
3. 标定在 320 trials 里不会漂移。

这三个默认在真实评测里都不成立。32 个任务里有 37.6 秒的长任务，有需要把手臂伸到工作空间边缘的收纳任务；评测跨 N 台机器人、共享 GPU、连续跑 320 trials；换机器人、碰撞、相机被碰一下都会让腕部伺服悄悄退化。此时再加一个更大的 VLA，边际收益远小于「决定何时换站姿、何时重规划、何时降频、何时校准」。

所以本轮押注 **BUDGET-GAIT**：

> 用一套可执行的指标体系，给时间、机械能、热/算力、标定置信度和可达性定「影子价格」；用一个离散站姿/微步态图，在当前手臂快够不到、扭矩余量快耗尽或保持功耗过高时，规划一次安全的站姿切换；用一个续航管理器，按「剩余预算还能不能撑到任务结束」来决定 VLA 规划、CHUNK-SERVO、站姿切换、恢复、保守模式和校准的节奏。

三个词不是三个模块，而是同一个执行器的三个视角：

| 灵感词 | 本轮的重新解释 | 落到哪里 | 不做什么 |
|---|---|---|---|
| **指标体系** | 不是仪表盘，而是**影子价格系统**：只保留能改变动作的领先指标 | 可达裕度、可操作度、扭矩裕度、稳定裕度、接触残差、计划有效期、标定残差、延迟/能量率 | 不堆砌滞后指标；不做第二个学习型打分器 |
| **步态规划** | 不是走到房间另一头，而是**桌面操作的可达性站姿图**：5–15 厘米的腰身/微步态 | 准静态站姿节点、安全转移边、可达/可操作/稳定/保持功耗约束、A* 短路径 | 不做高速行走；不在接触中乱动 base；不猜 pivot 语义 |
| **续航能力** | 不是电池百分比，而是**320 trials 的持续性能预算** | 时间、机械能、热/延迟、标定漂移、计划有效期的 TTE 与保守模式 | 不把续航简化成「省电」；不为省电牺牲必要精度 |

## 1. 思考轨迹：我先想到什么，又否定了什么

**第一个直觉：步态规划 = 走到更好的视角。**
我一开始想，既然腕部相机没有内参、头部双目有遮挡，不如让 G1 走到一个更好的观察位置。但这个想法很快被自己否掉：桌面任务的工作面是固定的，走动会移动相机、破坏已经标定的外参、增加 180 秒预算，而且挑战赛 README 对 `pivot` 的 7 维语义只写了「Lower-body / pivot target」，没有逐维定义。把整个方案押在未验证的 `pivot` 上，风险不对等。

于是我把它降级为**准静态站姿切换**，并分两级：

- **Class A：腰/躯干调整**（base 不动）。只改腰高、躯干俯仰、肩部朝向；base 系不变，不需要重新定位，风险最低。
- **Class B：5–15 厘米微步态**（base 移动）。只在 Class A 仍够不到、且 `pivot` 语义与视觉重定位都通过验证时启用；一旦重定位置信度低，退回上一站姿。

这样「步态」仍然是步态——它规划的是支撑/站姿序列，而不是一个静态姿态；但它是**桌面微步态**，不是房间级行走。

**第二个直觉：指标体系 = 成功率、步骤分、延迟的仪表盘。**
我一开始想做一个漂亮的监控面板。但仪表盘不改变动作，看到失败时已经晚了。真正有用的指标必须满足两条：

1. **领先**：在失败前几百毫秒就变化，而不是失败后才变化；
2. **可行动**：它跨过阈值时，能改变执行器的模式选择（换站姿、重规划、降频、校准、恢复）。

所以我给指标下了一个操作性定义：一个指标只有在「观测它之后，最优动作发生改变」时才有价值；否则不测。按这个标准，第一版只保留六个核心指标：可达裕度、扭矩裕度、计划有效期、标定置信度、接触残差、延迟/热余量。成功率/步骤分是滞后指标，只用于离线校准和竞赛组合，不进入在线闭环。

**第三个直觉：续航能力 = 电池。**
单次真机执行上限是 180 秒，电池几乎不可能是单次任务的瓶颈。真正会随 320 trials 累积的是：GPU 热/延迟漂移、相机标定漂移、计划有效期变短、工程调试预算被耗尽。所以我把「续航」重新定义为**持续性能预算**：

- 机械能预算：避免长时间高扭矩保持；
- 热/算力预算：避免 VLA 调用把 p99 延迟推高；
- 标定预算：用重投影残差监控漂移，及时校准或关闭伺服；
- 计划预算：用视觉变化率和计划分歧预测「这个 plan 还能用多久」；
- 竞赛预算：把工程时间投到 `q_t×Δ_t/(cost_t+能量+延迟)` 最高的任务。

这几个「预算」共享同一套 TTE（time-to-exhaustion）语言，才能被同一个执行器调度。

## 2. 上一轮留下的三个缺口

| 缺口 | 第 12 轮 CHUNK-SERVO 的做法 | 本轮的补法 |
|---|---|---|
| 身体固定 | 默认站姿不变，只动双臂 | 站姿图：Class A 腰/躯干，Class B 微步态；只在可达/扭矩/保持功耗触发时切换 |
| 执行节奏固定 | 提交时固定 `H_c=5` | 提交前选型 + 在线调度重规划/伺服/站姿；不假设能在评测中动态改 evaluator 的 chunk 语义 |
| 标定静态 | 一次性标定，假设不漂 | 标定置信度 + CUSUM 漂移检测；低置信度关 IBVS/回退 |
| 指标缺失 | 只有成功/步骤分/延迟 | 领先指标 + 预算 + 影子价格；只保留可行动指标 |
| 竞赛组合只看成功率 | `q_t×Δ/cost` | 加入能量/延迟成本，按持续性能排序 |
| 长任务高扭矩 | 没有显式建模 | 站姿目标里加入保持功耗项，长任务优先低扭矩站姿 |

**接口提醒**：挑战赛的 `action_chunk_size` 是提交时固定值；第 12 轮的「5 步」是提交时选的，不是评测中可在线改的。本轮的「自适应」严格分成两部分：

- **提交前**：在 `H_c∈{3,5,8,10}` 里选一个，依据单任务通道的 RTT/p99/成功率；
- **提交后**：固定 evaluator 的 chunk，在线只调度「plan 何时失效/何时重规划、伺服何时开/关、站姿何时切换」。这样不会违反接口，也不会把工程假设建在未证实的动态元数据上。

## 3. 核心假设（可证伪）

**H1（可达性杠杆）**：在长任务/远距离任务里，可达裕度、扭矩裕度和可操作度比 VLA 置信度更能预测失败；一次安全的 Class A 站姿切换带来的成功率增益，大于同等时间投给更大 VLA 的增益。

**H2（持续性能）**：320 trials 的成功率会因热/延迟漂移、标定漂移和计划过期而下降；预算感知的保守模式能在不损失平均成功率的前提下降低漂移。

**H3（指标稀疏性）**：大多数指标不可行动；少数几个（可达裕度、计划有效期、标定置信度、接触残差）驱动绝大多数模式切换。删掉其余指标不会显著改变决策。

**H4（分阶段风险）**：在安全和时间风险下，「指标-only → Class A → Class B」的分阶段 rollout 优于一次性全栈上线；如果 H1 不成立，指标-only 仍然是有价值的独立增量。

每条假设都对应产物区的门 G8–G11；不过门就不进入下一阶段。

## 4. 形式化草图

### 4.1 预算与影子价格

设第 \(t\) 个执行块开始时预算向量

\[
b_t=(b^T_t,b^E_t,b^H_t,b^C_t,b^G_t),
\]

分别表示剩余时间（s）、机械能（J）、热余量（归一化）、标定置信度（0–1）、算力/延迟余量（归一化）。消耗率

\[
c_t=(1,P_{\text{mech}},\alpha P_{\text{comp}},\nu_{\text{drift}},\gamma\ell_t).
\]

剩余可用时间

\[
\tau_i(t)=\frac{b^i_t}{\max(\epsilon,c^i_t-r^i_t)},
\]

其中 \(r^i_t\) 是恢复率（热散热、校准恢复、算力空转恢复）；热/算力预算归一化，\(H_t=1-b^H_t\)，\(\alpha,\gamma\) 把 W/ms 折算成归一化单位/秒。影子价格取

\[
\lambda_i(t)=\lambda_i^0\left(1+\frac{\tau_i^{\text{ref}}}{\max(\tau_i(t),\epsilon)}\right),
\]

其中 \(\tau_i^{\text{ref}}\) 是该预算的参考 TTE（离线设定，如时间 30s、热 60s、标定 120s），\(\lambda_i^0\) 是基准价格。预算越紧，价格越高。执行器不是「先成功率、再延迟」的硬编码优先级，而是用价格在 PLAN / SERVO / STANCE / RECOVER / CONSERVE / CALIBRATE 之间做市场式分配。

### 4.2 指标向量

\[
m_t=(g_t,\rho_t,\mu_t,\tau^{\text{tor}}_t,\sigma_t,\epsilon_t,\nu_t,\kappa_t,\ell_t,e_t,\eta_t),
\]

分别是：里程碑进度、可达裕度、可操作度、扭矩裕度、稳定裕度、接触/插入残差、计划有效期、标定置信度、延迟、能量率、编辑分数。每个指标都要给出「测量来源、更新频率、阈值、触发动作」；没有触发动作的指标不进在线闭环。

**可行动性**：指标 \(m_j\) 的决策价值定义为

\[
\mathrm{DV}(m_j)=\mathbb E\left[\max_a Q(a\mid m_j')-\max_a Q(a\mid m_j)\right],
\]

其中 \(m_j'\) 是观测到更多信息后的后验。工程上用离线敏感性分析近似：统计「该指标跨阈值时模式是否改变」的频率；频率低就删。

### 4.3 模式与决策

\[
\mathcal A=\{\text{PLAN},\text{SERVO},\text{STANCE},\text{RECOVER},\text{CONSERVE},\text{CALIBRATE},\text{SAFE\_HOLD}\}.
\]

安全过滤后的动作：

\[
a_t=\arg\max_{a\in\mathcal A_{\text{safe}}(b_t,s_t)}
\left[\Delta S(a)-\lambda_t^\top\Delta b(a)\right],
\]

其中 \(\Delta S(a)\) 是里程碑进度/成功可行性的期望增量，\(\Delta b(a)\) 是该动作持续时间的预算消耗。STANCE 的 \(\Delta S\) 包含「切换后可达裕度/扭矩裕度的提升」，\(\Delta b\) 包含转移时间、能量、场景扰动风险。PLAN 的 \(\Delta S\) 包含计划有效期提升，\(\Delta b\) 包含一次 VLA 调用的延迟/热成本。

这是一个约束半马尔可夫决策过程；精确求解不现实。产物区用**安全过滤 + 一步预算 rollout + 站姿图最短路**的层次化近似，不引入第二个学习模型。

### 4.4 站姿图

节点 \(q_s=(x_b,y_b,\theta_b,h_w,\phi_t,\text{foot})\)，边是准静态可执行转移。每个节点预计算：

- 可达裕度 \(\rho(q_s,T)\)：目标到手臂工作空间边界的带符号距离；
- 可操作度 \(\mu(q_s,T)\)：目标 IK 处 \(\sqrt{\det(JJ^\top)}\) 的归一化值；
- 扭矩裕度 \(\tau^{\text{tor}}(q_s,T)=1-\max_i|\tau_i|/\tau_i^{\max}\)；
- 稳定裕度 \(\sigma(q_s)\)：CoM 投影到支撑多边形边界的最小距离；
- 保持功耗 \(P_{\text{hold}}(q_s)\)：维持该站姿的等效重力扭矩功率。

站姿路径目标：

\[
J(q_{0:K})=\sum_{k=0}^{K-1}\left(\lambda_t t_k+\lambda_e E_k+\lambda_d D_k+\lambda_r R_k\right)
+\lambda_h P_{\text{hold}}(q_K)\hat\tau_{\text{remain}},
\]

约束：目标可达、\(\mu\ge\mu_{\min}\)、\(\tau^{\text{tor}}\ge\tau^{\text{tor}}_{\min}\)、每步 \(\sigma\ge\sigma_{\min}\)、转移时间不超过剩余时间减安全停止时间。最后一项是续航项：长任务更愿意多花一点转移成本，换一个低扭矩站姿。

### 4.5 执行节奏

挑战赛的 chunk 是提交时固定的，所以这里的「节奏」不是在线改 `action_chunk_size`，而是三件事：

1. **提交前**在 `H_c∈{3,5,8,10}` 里选型；
2. 在线决定 plan 的有效期与重规划时机；
3. 在线决定伺服开关/增益、站姿切换、保守/校准模式。

如果未来官方允许动态元数据，再把「按预算调 chunk」作为扩展；本轮不把这个未证实能力当基础。

## 5. 算法一句话与主循环

**BUDGET-GAIT**：在每个执行块，用指标体系更新预算和影子价格；先过安全/预算过滤；若当前站姿不可达、扭矩/稳定裕度不足或保持功耗过高，则用 A* 在站姿图上找一条安全路径并执行第一步；否则按计划有效期决定重规划，按热/能量 TTE 决定保守模式，按标定置信度决定是否校准/关闭伺服；最后把 CHUNK-SERVO 的 5 步动作叠加伺服修正返回。

```text
BUDGET-GAIT(obs, task, budgets, stance_graph):
  m ← update_metrics(obs)
  b ← update_budgets(obs, m)
  λ ← shadow_prices(b)

  if unsafe(b, m): return SAFE_HOLD
  if κ < κ_min: return CALIBRATE_or_disable_servo
  if edit_score > θ_e: return RECOVER

  if reach_deficit(m) or torque_deficit(m) or holding_cost_high(m):
      q* ← A*(stance_graph, q_now, target, λ)
      if J(q*) < J_keep and safe_transition(q_now, q*):
          return STANCE(q*)

  if plan_expired or plan_endurance < H_c/f_c + RTT:
      request_plan_async(obs)

  if thermal_TTE < horizon or energy_TTE < horizon:
      enter_CONSERVE()

  return CHUNK_SERVO(plan, obs, H_c, λ)
```

## 6. 与第 12 轮的关系：保留 / 升级 / 剪枝

**保留**：官方 WLA 6B 基座、30 步 plan、5 步伺服、演示检索相对目标、GEO-RESIDUAL 的接触/编辑检测、数字孪生标定、单任务通道、A/B 统计。

**升级**：

- 固定站姿 → 站姿图（Class A/B）；
- 固定 `H_c=5` → 提交前选型 + 在线计划/伺服调度；
- 静态标定 → 标定置信度 + CUSUM；
- 成功率组合 → 带能量/延迟成本的持续性能组合；
- 「成功了没有」→「距离失败还有多远 + 距离预算耗尽还有多久」。

**剪枝**：

- 不做房间级行走；不做高速步态；不在接触中切 base；
- 不做第二个学习模型/学习型成功预测器；指标阈值用离线分位数/共形校准；
- 不做完整 sim-to-real 策略训练；站姿图只在 URDF/仿真里验证；
- 不把 `pivot` 当已证实接口；Class B 必须先在单任务通道验证；
- 不为续航牺牲必要精度；保守模式只在预算确实紧时触发。

## 7. 实验门：先证明指标有用，再证明站姿有用

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G8 | 指标是否领先且可行动？ | 失败前 AUROC ≥0.8；误报 ≤10%；检测延迟 ≤300ms；≥70% 的模式切换由 ≤5 个指标驱动 | 删指标；退回 CHUNK-SERVO |
| G9 | 站姿是否有净收益？ | 长任务/远距离任务 ≥2 个 +10pp；能量/成功 ↓≥10%；基线任务不回归 >5pp | 砍掉站姿层，只保留指标+续航 |
| G10 | 320 trials 是否续航稳定？ | 成功率漂移 ≤3pp；p99 延迟漂移 ≤20%；无热节流；标定告警有效 | 降频/加 chunk/加校准 |
| G11 | 站姿是否安全合规？ | 0 次稳定裕度越界；0 碰撞；安全停止时间 < 剩余时间；单模型解释通过 | 回退 Class A 或禁用站姿 |

分阶段上线：

1. **Stage 0**：WLA + CHUNK-SERVO 基线；
2. **Stage 1**：指标-only（安全，必做；即使站姿失败也保留）；
3. **Stage 2**：Class A 腰/躯干站姿；
4. **Stage 3**：Class B 微步态（只有 G9/G11 全过才启用）。

## 8. 本轮最大的风险

最大风险是：桌面任务里站姿/微步态的净收益可能小于它引入的扰动、时间成本和 `pivot` 语义不确定性——如果 G9 在长任务上不涨点，就应把 BUDGET-GAIT 退化为「指标门控 + 续航预算」的轻量执行器，砍掉站姿层。

# 第 13 轮产物 · BUDGET-GAIT 技术报告

> 复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告承接第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO；不替换前作，而是在控制环之上加一层**资源感知执行器**。A 级事实沿用 **2026-10-28** 的核对；本轮不新增未核实的外部声明，新增内容为设计与推导（C 级）。

## 0. 结论与边界

### 0.1 一句话结论

第 12 轮把「最后 3 厘米」从开环变成 167ms 闭环；本轮解决它上面的三个资源问题：**身体站姿、执行节奏、持续性能**。BUDGET-GAIT 用指标体系统一给时间、机械能、热/算力、标定和可达性定影子价格，用离散站姿/微步态图只在净收益为正时改变身体，用 TTE/预算约束把 320 trials 的持续性能纳入决策；不新增学习模型，站姿规划是确定性图搜索，伺服仍是 CHUNK-SERVO。

### 0.2 证据等级

| 等级 | 含义 | 本报告例子 |
|---|---|---|
| A | 官方文档/数据/API 直接核实，沿用第 12 轮 | 32 任务、10 次/任务、180s、四路 RGB、无深度/力、chunk 固定、WLA 6B/30 步、33,276 eps |
| B | 公开数据上的可复现分析，沿用第 12 轮 | 榜单 `step~success` 回归、任务时长统计 |
| C | 本轮设计假设，需 G8–G11 验证 | 站姿净收益、指标 AUROC、能量代理、TTE 阈值 |

### 0.3 本轮不做什么

- 不做房间级行走/高速步态；不做接触中的 base 移动。
- 不做第二个学习模型/学习型成功预测器；指标阈值用离线统计/共形校准。
- 不做完整 sim-to-real 策略训练；站姿图只在 URDF/仿真里验证。
- 不假设 `pivot` 语义；Class B 必须单任务通道先验证。
- 不把续航简化成省电；不为省电牺牲必要精度。
- 不替换 CHUNK-SERVO；只在它上面加执行器。

## 1. 继承事实与新增约束

### 1.1 继承的硬约束（A）

| 约束 | 内容 | 对 BUDGET-GAIT 的影响 |
|---|---|---|
| 单模型 | 32 任务须同一模型；不得混合多个模型 | 站姿规划必须确定性；指标阈值是离线校准，不是在线学习策略 |
| 任务/次数 | 32 任务 ×10 次；5 类泛化各 2 次 | 站姿收益要按任务族/泛化轴评估；human 轴要能暂停/恢复 |
| 时限 | 单次 ≤180s | 时间预算是硬约束；站姿转移必须可安全停止 |
| 部署 | N 台机器人、8765 起 N 个连续端口、reset 隔离 | 每端口独立预算/站姿状态；共享 VLA 但权重一份 |
| 观测 | 四路 RGB 480×640；无 depth/camera_info/force/tactile | 可达/稳定/能量只能用本体+RGB+URDF 估计；不能依赖力/深度 |
| 动作 | `ee` 或 `joint` 互斥；EE 绝对位姿；`pivot` 7D；`lower_body` 15D | 站姿动作要映射到 pivot/lower_body；语义未证实，需回退 |
| chunk | `action_chunk_size` 提交时固定；chunk 内无新观测 | 不能假设在线改 evaluator 的 chunk 语义；自适应只能体现在提交前选型与在线重规划/伺服/站姿调度 |
| 基座 | WLA 30 步 @30Hz；官方 6B；33k 演示 | 保留 30 步 plan + 5 步伺服；站姿切换会移动相机，需重定位/重规划 |

**接口澄清**：第 12 轮的「5 步执行块」是**提交时**选的 `action_chunk_size=5`，不是评测中可动态改写的参数。本报告默认 `H_c=5` 固定；在线只改变：

1. plan 的有效期与重规划时机；
2. 伺服开关/增益；
3. 站姿切换；
4. 保守/恢复/校准模式。

如果未来确认官方允许动态元数据，再把「按预算调 chunk」作为扩展。本轮不把未证实能力当基础。

### 1.2 新增设计约束（C）

1. 站姿切换必须准静态、可中止、可回到上一安全站姿。
2. Class A（腰/躯干）优先；Class B（base 移动）只在 `pivot` 语义和视觉重定位验证后启用。
3. 站姿切换会使头部/腕部相机运动，必须重新锚定目标；Class B 还需要 base 位移估计。
4. 能量/热是代理量；必须用台架/日志校准，不能把代理当真实电池。
5. 指标阈值必须用离线成功/失败数据校准；在线只用阈值和 CUSUM，不训练新模型。
6. 任何站姿切换前必须满足时间安全不变式：剩余时间 ≥ 转移时间 + 安全停止时间 + 一个执行块。

### 1.3 关键未核实项

- `pivot` 7 维的逐维语义；挑战赛是否允许/鼓励 base 移动；`reset()` 是否恢复 base 位姿。
- 评测端实际控制频率（本报告假设 30Hz；必须实测）。
- 网络 RTT 分布；共享 GPU 的热/延迟特性。
- 腕部相机内参；头双目在站姿变化后的外参恢复精度。
- 官方 WLA 与挑战赛 API 的 EE 帧/TCP 偏移。
- 320 trials 的真实失败分布（榜单是预览，不能反推）。

### 2.1 状态、观测、动作

- 机器人状态 \(s_t=(q_t,\dot q_t,\mathrm{gr}_t,b_t)\)：关节、速度、夹爪、预算。
- 观测 \(o_t=(I^{\text{head}}_t,I^{\text{wrist}}_t,x^{\text{ee}}_t,\text{lang})\)：四路 RGB、EE 位姿、语言；无深度/力。
- 动作 \(a_t=(a^{\text{arm}}_t,a^{\text{grip}}_t,a^{\text{stance}}_t)\)：
  - \(a^{\text{arm}}_t\)：CHUNK-SERVO 产生的 EE 绝对位姿序列；
  - \(a^{\text{grip}}_t\)：夹爪；
  - \(a^{\text{stance}}_t\)：pivot/lower_body 的准静态站姿目标（Class A/B）。
- 执行块 \(H_c\)：提交时固定的 chunk 长度（默认 5）；\(f_c\) 控制频率（假设 30Hz）。

### 2.2 预算向量与 TTE

定义

\[
b_t=(b^T_t,b^E_t,b^H_t,b^C_t,b^G_t)\in\mathbb R_+^5,
\]

- \(b^T\)：剩余时间（s）；
- \(b^E\)：剩余机械能（J，代理）；
- \(b^H\)：热余量（归一化，1=冷，0=节流）；
- \(b^C\)：标定置信度（0–1）；
- \(b^G\)：算力/延迟余量（归一化，1=充足，0=超时边缘）。

消耗率

\[
c_t=(1,P_{\text{mech}},\alpha P_{\text{comp}},\nu_{\text{drift}},\gamma\ell_t),
\]

恢复率

\[
r_t=(0,0,\beta H_t,r_{\text{cal}},r_{\text{comp}}).
\]

热/算力预算统一归一化：\(H_t=1-b^H_t\in[0,1]\) 是归一化热状态（0=环境温度，1=节流阈值），\(\alpha,\gamma\) 把 W/ms 折算成归一化单位/秒；时间/能量预算保留 s/J 单位。

预算动力学：

\[
b_{t+1}=\mathrm{clip}\left(b_t-(c_t-r_t)\Delta t,\ 0,\ b_{\max}\right).
\]

TTE：

\[
\tau_i(t)=\frac{b^i_t}{\max(\epsilon,c^i_t-r^i_t)}.
\]

时间预算不恢复；能量在 trial 内不恢复；热/算力可恢复；标定只在 CALIBRATE 时恢复。

### 2.3 指标向量

\[
m_t=(g_t,\rho_t,\mu_t,\tau^{\text{tor}}_t,\sigma_t,\epsilon_t,\nu_t,\kappa_t,\ell_t,e_t,\eta_t),
\]

| 指标 | 定义 | 来源 | 触发 |
|---|---|---|---|
| \(g_t\) | 里程碑进度，0–1 | 任务里程碑图 + 几何完成判据 | 成功可行性/步骤分 |
| \(\rho_t\) | 带符号可达裕度（m） | URDF + 目标位姿 + 逆运动学 | STANCE |
| \(\mu_t\) | 归一化可操作度 | \(J\) 的最小奇异值/\(\sqrt{\det(JJ^\top)}\) | STANCE/降速 |
| \(\tau^{\text{tor}}_t\) | 扭矩裕度 \(1-\max_i|\tau_i|/\tau_i^{\max}\) | 逆动力学代理 | STANCE/降速 |
| \(\sigma_t\) | 稳定裕度（m） | CoM 投影到支撑多边形边界 | SAFE_HOLD/STANCE |
| \(\epsilon_t\) | 接触/插入残差（m） | 第 11 轮几何 | 接触段降增益 |
| \(\nu_t\) | 计划有效期（s） | 视觉变化率 + 计划分歧 | PLAN |
| \(\kappa_t\) | 标定置信度（0–1） | 重投影/极线残差 | CALIBRATE/关伺服 |
| \(\ell_t\) | 延迟（ms） | 时间戳/RTT | CONSERVE/PLAN |
| \(e_t\) | 机械能率（W） | 逆动力学/代理 | CONSERVE/STANCE |
| \(\eta_t\) | 编辑分数 | 第 11 轮 GEO-RESIDUAL | RECOVER |

**领先性**：\(g_t\) 是滞后/半滞后；\(\rho,\mu,\tau^{\text{tor}},\sigma,\nu,\kappa,\ell,e,\eta\) 是领先指标。在线闭环只用领先指标；\(g_t\) 用于离线校准和竞赛组合。

**可行动性**：定义决策价值

\[
\mathrm{DV}(m_j)=\mathbb E_{m_j'\sim p(\cdot\mid m_j)}
\left[\max_{a\in\mathcal A}Q(a\mid m_j')-\max_{a\in\mathcal A}Q(a\mid m_j)\right].
\]

工程近似：离线统计「指标跨阈值 → 模式改变」的频率；低于 5% 的指标删除。第一版只保留 \(\rho,\tau^{\text{tor}},\nu,\kappa,\epsilon,\ell\) 六个核心指标；\(\mu,\sigma,\eta,e\) 作为安全/续航辅助。

### 2.4 影子价格

\[
\lambda_i(t)=\lambda_i^0\left(1+\frac{\tau_i^{\text{ref}}}{\max(\tau_i(t),\epsilon)}\right).
\]

其中 \(\tau_i^{\text{ref}}\) 是该预算的参考 TTE（离线设定，例如时间 30s、热/延迟 60s、标定 120s），\(\lambda_i^0\) 是基准价格。

含义：

- 时间紧 → \(\lambda_T\) 升 → 少做昂贵站姿/重规划，优先完成；
- 热/延迟紧 → \(\lambda_H,\lambda_G\) 升 → 降 VLA 调用/降分辨率/进入保守模式；
- 标定低 → \(\lambda_C\) 升 → CALIBRATE 或关 IBVS；
- 可达差 → 站姿的 \(\Delta S\) 升 → STANCE 变得划算。

价格不是手调优先级，而是预算约束的拉格朗日乘子近似；离线用仿真扫参，在线按 TTE 调制。

### 2.5 模式与目标

\[
\mathcal A=\{\text{PLAN},\text{SERVO},\text{STANCE},\text{RECOVER},\text{CONSERVE},\text{CALIBRATE},\text{SAFE\_HOLD}\}.
\]

\[
a_t=\arg\max_{a\in\mathcal A_{\text{safe}}(b_t,s_t)}
\left[\Delta S(a)-\lambda_t^\top\Delta b(a)\right],
\]

\[
\mathcal A_{\text{safe}}=\{a:\ \sigma(q_{t+1})\ge\sigma_{\min},\ \text{joint/collision OK},\ 
b^T_t\ge t_{\text{stop}}(a)+t_{\text{trans}}(a)+H_c/f_c\}.
\]

\(\Delta S(a)\) 的估计：

- **里程碑图**：每个任务离线定义 3–8 个几何里程碑（抓取、提升、接近、插入、放置、关闭等）；在线用几何判据/相位估计完成度。
- **成功可行性**：如果剩余时间 < 估计剩余任务时间 + 安全停止，则成功不可行，转为「保住步骤分」的保守策略。
- **STANCE**：切换后可达裕度/扭矩裕度/可操作度提升带来的里程碑完成概率增量；用离线仿真/演示标定一个单调映射，不是学习策略。
- **PLAN**：计划有效期提升，减少「旧计划追错目标」的概率。
- **SERVO**：接触/插入精度提升。
- **RECOVER**：避免因编辑导致的灾难失败。
- **CONSERVE**：通常为负，但降低预算消耗，避免后面更大的失败。
- **CALIBRATE**：恢复感知有效性，避免伺服追错。

这是一个约束半马尔可夫决策过程；精确求解不可行。下面用层次化近似。

### 2.6 站姿图

节点：

\[
q_s=(x_b,y_b,\theta_b,h_w,\phi_t,\text{foot}_L,\text{foot}_R).
\]

Class A：\(x_b,y_b,\theta_b\) 固定，只变 \(h_w,\phi_t\)（腰高、躯干俯仰/侧倾）。Class B：允许 \(x_b,y_b,\theta_b\) 小范围变化，foot placements 随之调整。

节点属性：

- 可达集 \(W(q_s)\)：手臂在工作空间中的可达位姿集合；
- 可达裕度：
  \[
  \rho(q_s,T)=
  \begin{cases}
  \min_{x\in\partial W(q_s)}\|p_T-x\|, & T\in W(q_s),\\
  -\min_{x\in\partial W(q_s)}\|p_T-x\|, & T\notin W(q_s);
  \end{cases}
  \]
- 可操作度：
  \[
  \mu(q_s,T)=\frac{\sqrt{\det(J(q_{\text{IK}})J(q_{\text{IK}})^\top)}}{\mu_{\max}};
  \]
- 扭矩裕度：
  \[
  \tau^{\text{tor}}(q_s,T)=1-\max_i\frac{|\tau_i|}{\tau_i^{\max}},
  \quad \tau=M(q)\ddot q+C(q,\dot q)\dot q+g(q);
  \]
- 稳定裕度：
  \[
  \sigma(q_s)=\min_{e\in\partial P}\|p_{\text{CoM}}-e\|_2;
  \]
- 保持功耗：
  \[
  P_{\text{hold}}(q_s)=\sum_i \tau_i^{g}(q_s)^2 R_i+P_0,
  \]
  其中 \(\tau^g\) 是重力/支撑扭矩，\(R_i\) 是等效关节热阻/损耗系数；没有热参数时用 \(\sum_i|\tau_i^g|\) 做排序代理。长任务用 \(P_{\text{hold}}\hat\tau_{\text{remain}}\) 计入目标，\(\hat\tau_{\text{remain}}\) 用任务演示时长统计或剩余时间预算估计。

边 \(u=(q_s,q_s')\) 的成本：

\[
c(q_s,q_s')=\lambda_t t_{\text{trans}}+\lambda_e E_{\text{trans}}
+\lambda_d D_{\text{trans}}+\lambda_r R_{\text{trans}},
\]

其中 \(D_{\text{trans}}\) 是场景扰动（相机运动、桌面振动、物体位移风险），\(R_{\text{trans}}\) 是失稳/碰撞风险。Class B 的 \(D\) 显著高于 Class A。

站姿路径目标：

\[
J(q_{0:K})=\sum_{k=0}^{K-1}c(q_k,q_{k+1})
+\lambda_h P_{\text{hold}}(q_K)\hat\tau_{\text{remain}},
\]

约束：

\[
\rho(q_K,T)\ge\rho_{\min},\quad
\mu(q_K,T)\ge\mu_{\min},\quad
\tau^{\text{tor}}(q_K,T)\ge\tau^{\text{tor}}_{\min},\quad
\sigma(q_k)\ge\sigma_{\min}\ \forall k.
\]

如果当前站姿已经满足约束且 \(J_{\text{keep}}\le J(q^*)\)，不切换。只有「净收益为正」才动身体。

### 2.7 自适应执行节奏

由于提交 chunk 固定，在线「节奏」只体现在重规划/伺服/站姿调度。设计划有效期为 \(\hat T_{\text{plan}}\)，RTT 为 \(\tau_{\text{RTT}}\)，则重规划条件：

\[
\hat T_{\text{plan}} < H_c/f_c+\tau_{\text{RTT}}
\quad\Rightarrow\quad \text{request PLAN}.
\]

保守模式条件：

\[
\min_i \tau_i(t) < H_c/f_c+\tau_{\text{RTT}}+t_{\text{margin}}
\quad\Rightarrow\quad \text{CONSERVE}.
\]

提交前可以用同一目标在 \(H\in\{3,5,8,10\}\) 中选一个固定值；如果未来允许在线动态 chunk，则把 \(H_c\) 作为在线决策变量，目标为

\[
H_c^*=\arg\min_{H\in\{3,5,8,10\}}
\left[\alpha\frac{H}{f_c}+\beta\tau_{\text{RTT}}
+\gamma\mathbf 1[\text{replan}]+\delta\,\text{risk}(H)\right],
\]

约束 \(H/f_c+\tau_{\text{RTT}}\le T_{\text{fb}}^{\max}\)。本轮不依赖在线动态能力。

## 3. 系统设计

### 3.1 架构

```text
Evaluator (N ports)
   │ websocket obs/action
   ▼
Per-port BUDGET-GAIT Executive (CPU)
   ├─ metric updater (reach/torque/stability/plan/calibration/latency/energy)
   ├─ budget & shadow-price manager
   ├─ stance graph + A* planner (Class A/B)
   ├─ mode selector (safety filter + one-step budget rollout)
   ├─ plan cache / replan scheduler
   └─ CHUNK-SERVO adapter (30-step plan + 5-step servo)
   │ async
   ▼
Shared VLA server (GPU, WLA 6B)
```

- 每端口独立预算、指标、站姿、plan cache、`reset()`。
- 共享 VLA 只保留一份权重；按 session ID 隔离。
- 站姿/指标/规划在 CPU；不抢 GPU。
- 任何异常 → SAFE_HOLD/上一合法 chunk。

### 3.2 接口与动作适配

- `control_space="ee"`；EE 绝对位姿 xyz+rpy；gripper；pivot 7D。
- WLA 54D → 挑战赛 21D 的 adapter 沿用第 12 轮：
  - 先把 30 步相对 EE compose 成 base 系绝对目标；
  - 再按固定 chunk 切片；
  - gripper 直通；
  - pivot 从 base/waist/height 组合；语义未证实时返回零 pivot（只验证双臂）。
- 站姿动作：
  - **Class A**：只改 waist/torso/height 对应的维度；base 不动；EE 目标仍在同一 base 系。
  - **Class B**：改 base x/y/yaw；需要视觉重定位；若重定位置信度 < 阈值，回退上一站姿。
- 站姿切换期间：
  1. 双臂退到安全收拢位；
  2. 暂停 CHUNK-SERVO；
  3. 以低速执行站姿转移；
  4. 监控稳定裕度/跟踪误差；
  5. 到达后重新锚定目标（Class A：用 `state_d435` + 腰部正运动学；Class B：头双目视觉重定位）；
  6. 使 plan 失效；必要时 VLA 重规划；
  7. 恢复伺服。

### 3.3 主循环伪代码

每个执行块的算法步骤：

1. **观测与指标**：更新 \(m_t\)（可达/扭矩/稳定/接触/计划/标定/延迟/能量）。
2. **预算与价格**：更新 \(b_t\)、TTE \(\tau_i(t)\)、影子价格 \(\lambda_t\)。
3. **安全门控**：若稳定/碰撞/时间不变式不满足，返回 SAFE_HOLD。
4. **感知/编辑门控**：标定置信度低 → CALIBRATE 或关伺服；编辑分数高 → RECOVER。
5. **站姿触发**：若可达/扭矩/保持功耗赤字，A* 找站姿路径；净收益为正且安全才执行。
6. **计划/续航调度**：计划有效期不足 → 异步重规划；热/能量 TTE 不足 → CONSERVE。
7. **执行**：否则返回 CHUNK-SERVO 的固定 chunk 动作，叠加伺服修正。

```python
class BudgetGaitPolicy:
    def get_action(self, obs):
        m = self.metrics.update(obs)
        b = self.budgets.update(obs, m)
        lam = self.prices.from_tte(b)

        if self.safety.violated(m, b):
            return self.safe_hold(obs)
        if m.kappa < self.kappa_min:
            return self.calibrate_or_disable_servo(obs)
        if m.edit_score > self.theta_e:
            return self.recover(obs)

        if self.stance.trigger(m, b):
            path = self.stance.plan(obs.target, lam)
            if path and self.stance.net_gain(path) > 0:
                return self.stance.execute_first(path, obs)

        if self.plan.expired(m) or m.plan_endurance < self.Hc / self.fc + self.rtt:
            self.plan.request_async(obs)

        if self.budgets.tte_low(b, horizon=self.Hc / self.fc + self.rtt):
            self.mode = "CONSERVE"

        return self.chunk_servo(obs, self.plan, self.Hc, lam)
```

### 3.4 状态机

| 状态 | 进入条件 | 行为 | 退出 |
|---|---|---|---|
| INIT | reset | 清预算/指标/plan/站姿 | 首帧观测 |
| PLAN | plan 过期/无效 | 异步 VLA；旧 plan + 伺服兜底 | plan ready |
| SERVO | 正常 | CHUNK-SERVO | 接触/编辑/预算触发 |
| STANCE | 可达/扭矩/保持功耗触发且净收益正 | 收臂→转移→重定位→重规划 | 到达/中止 |
| RECOVER | 编辑分数 > θ | 停→重定位→更新目标/重规划 | 恢复/失败 |
| CONSERVE | 热/能量 TTE < horizon | 降 VLA 频率/分辨率/速度，保持站姿 | 预算恢复/任务结束 |
| CALIBRATE | 标定置信度 < κ_min | 重投影校准；失败则关伺服 | 置信度恢复 |
| SAFE_HOLD | 稳定/碰撞/时间安全越界 | 停止，保持安全姿态 | 人工/重试 |
| DONE | 成功/超时/max steps | 清理，等待 reset | reset |

### 3.5 与 CHUNK-SERVO 的集成

- VLA 仍输出 30 步 plan；CHUNK-SERVO 仍每 5 步（提交时固定 chunk）做一次伺服。
- BUDGET-GAIT 不改变 evaluator 的 chunk 语义；它改变：
  - plan 的重规划时机；
  - 伺服增益/开关；
  - 站姿；
  - 是否进入保守/恢复/校准。
- 站姿切换后 plan 失效：
  - Class A：base 系不变，但头部/腕部相机外参变了；相对目标 \(T_{\text{base,target}}\) 需要重新估计；EE 目标可保留，但 plan 的图像上下文变了，建议重新规划或至少重新锚定。
  - Class B：base 系变了；必须重定位目标并重规划。
- 如果站姿切换失败/中止：回到上一站姿，恢复旧 plan（若相机外参可恢复），否则重规划。

## 4. 指标体系实现

### 4.1 测量与更新

| 指标 | 测量 | 频率 | 成本 |
|---|---|---|---|
| \(\rho\) | 目标位姿 + URDF IK/工作空间网格 | 每 chunk | <1ms |
| \(\mu\) | IK 解 + 雅可比 | 每 chunk | <1ms |
| \(\tau^{\text{tor}}\) | 逆动力学（状态+加速度） | 每 chunk | 1–3ms |
| \(\sigma\) | CoM + 支撑多边形 | 每 chunk | <1ms |
| \(\epsilon\) | 第 11 轮几何 | 每 chunk | 1–2ms |
| \(\nu\) | 光流/编辑分数 + plan 分歧 | 每 chunk | 1–5ms |
| \(\kappa\) | 重投影/极线残差 | 每 5 chunks | 2–5ms |
| \(\ell\) | 时间戳 | 每次调用 | O(1) |
| \(e\) | 逆动力学/代理 | 每 chunk | 1–3ms |
| \(\eta\) | GEO-RESIDUAL | 每 chunk | 1–2ms |

总 CPU 开销 <5ms/chunk，远小于 167ms 执行块。

### 4.2 阈值校准

- 离线收集成功/失败轨迹（33k 成功演示 + 仿真注入失败 + 单任务通道失败）。
- 对每个指标，取成功轨迹的分位数 \(\theta_j=Q_{1-\alpha}(m_j)\)；在失败轨迹上测检测率/延迟。
- 共形校准：在成功校准集上取 \((1-\alpha)\) 分位数，保证新成功轨迹的边际误报率 ≤ α（可交换性假设）。
- 分布漂移：CUSUM 监控指标均值/方差；漂移时重新校准或提高阈值。
- 不训练分类器；阈值是统计量，不是第二个模型。

### 4.3 可行动性筛选

离线做「阈值敏感性」：

1. 对每个指标，模拟它在成功轨迹上跨阈值；
2. 看模式选择是否改变；
3. 统计改变频率和收益；
4. 删除低 DV 指标，减少复杂度和误报。

预期保留：\(\rho,\tau^{\text{tor}},\nu,\kappa,\epsilon,\ell\)。\(\mu,\sigma,\eta,e\) 作为安全/续航辅助，不单独触发模式。

### 4.4 成功可行性

- 任务里程碑图：离线把官方 rubric 的 94 个评分步骤映射到 32 个任务的 3–8 个几何里程碑。
- 在线 \(g_t\)：用几何判据（抓取闭合、物体提升、目标距离、插入深度、放置稳定）估计完成度；无法几何判据的任务用 VLA 相位/计划分歧。
- 剩余时间估计：
  \[
  \hat T_{\text{remain}}=\sum_{j\in\text{remaining}}\hat t_j/\text{speed}
  \]
  \(\hat t_j\) 来自演示时长统计；speed 来自当前预算/保守模式。
- 如果 \(b^T_t<\hat T_{\text{remain}}+t_{\text{stop}}\)：成功不可行 → 保守模式，优先保住已完成的步骤分，避免灾难失败。
- 注意：成功仍是第一优先级；只有在成功不可行时才转向步骤分。

## 5. 站姿/微步态规划

### 5.1 图构建

离线：

1. 从 G1 URDF + Dex1 建立关节限位、自碰撞、桌面碰撞模型。
2. 离散化：
   - 腰高 \(h_w\in\{0,0.05,0.10\}\) m（相对标称）；
   - 躯干俯仰 \(\phi_t\in\{-10°,0°,10°\}\)；
   - 躯干侧倾 \(\phi_r\in\{-5°,0°,5°\}\)；
   - Class B：base \(x,y\in\{-0.10,-0.05,0,0.05,0.10\}\) m，yaw \(\in\{-10°,0°,10°\}\)；
   - 脚位：固定/小步网格。
3. 过滤不可行节点：关节限位、自碰撞、桌面碰撞、稳定裕度 < σ_min、相机视野不足。
4. 对每个节点采样手臂工作空间，预计算可达网格/边界；对目标区域预计算 IK/可操作度/扭矩裕度。
5. 边：相邻节点；Class A 是腰/躯干连续小转移；Class B 是准静态微步（一脚支撑、一脚短距离移动）。
6. 预计算转移时间、能量、扰动、风险。

在线：目标位姿 \(T_t\) 变化时，查表/插值得到每个节点的 \(\rho,\mu,\tau^{\text{tor}}\)；A*/Dijkstra 在小子图上找最优路径。

### 5.2 可达/可操作/扭矩

- 可达：用采样工作空间或解析臂长近似；目标在边界内则正裕度，否则负裕度。
- 可操作：目标 IK 解 \(q_{\text{IK}}\) 处 \(J\) 的最小奇异值；多解取最大。
- 扭矩：逆动力学在慢速标称轨迹上的峰值扭矩；外部接触力未知，用保守系数（如 1.2–1.5）放大。
- 稳定：CoM 投影到支撑多边形；准静态假设；快速转移时用 ZMP 余量。
- 保持功耗：准静态保持时关节速度近零，用「保持扭矩的等效热功率」\(\sum_i \tau_i^2 R_i\) 或 \(\sum_i|\tau_i|\) 的排序代理。没有电流/力矩传感，\(P_{\text{hold}}\) 是代理；用 URDF 重力扭矩 + 关节额定电流估算。

### 5.3 规划与执行

- 规划：A*，启发式 \(h(q)=\max(0,\rho_{\min}-\rho(q))+\alpha t_{\text{trans}}\)；图小，Dijkstra 也可。若把保持功耗的终端代价计入，启发式需加对应的下界；图很小时直接用 Dijkstra 更稳妥。
- 重规划：每 1–3 个 chunk 或目标大变化时；站姿切换后立即重评估。
- 执行：
  1. 安全收臂（退到胸前/侧方，避开桌面）；
  2. 检查稳定裕度、时间预算、接触状态；
  3. 低速执行第一步；
  4. 监控跟踪误差/稳定裕度/相机抖动；
  5. 异常 → 中止，回上一站姿；
  6. 到达 → 重定位 → 重规划 → 恢复伺服。
- 禁止：接触中切 base；高动态任务切站姿；标定置信度低时切 Class B；剩余时间不足时切站姿。

### 5.4 为什么这是「步态规划」

- 它规划的是支撑/站姿序列 \(q_{0:K}\)，每一步都有支撑多边形、稳定裕度和转移代价；这正是准静态步态规划的定义，只是步长是 5–15 厘米、目标是桌面操作而不是 locomotion。
- Class A 是「姿势步态」；Class B 是「微步态」。两者共享图搜索/稳定性/能量代价，不需要第二套算法。
- 与行走的区别：不追求速度/步幅，只追求可达性、稳定性和保持功耗；不做动态平衡，全部准静态。

## 6. 续航管理

### 6.1 机械能

\[
P_{\text{mech}}(t)=\sum_i|\tau_i(t)\dot q_i(t)|+P_0.
\]

- \(\tau\) 用 URDF 逆动力学估计；没有力矩传感，忽略外部接触力或用保守放大。
- 备选代理：
  \[
  P_{\text{proxy}}=\sum_i\left(a_i\dot q_i^2+b_i|\dot q_i|+c_i|\ddot q_i|\right)+P_0,
  \]
  系数用台架功率计/日志拟合；没有台架就只用相对排序，不报绝对焦耳。
- \(E_{\text{trial}}=\int P\,dt\)；预算 \(E_{\max}\) 由电池/热约束给；单次 180s 内通常不是硬瓶颈，但长任务/高扭矩站姿会显著增加。

### 6.2 热/算力

- 一阶模型（\(H_t\in[0,1]\) 为归一化热状态，0=环境温度，1=节流阈值）：
  \[
  H_{t+1}=H_t+\alpha P_{\text{comp}}\Delta t-\beta H_t\Delta t.
  \]
- 可观测量：GPU 温度/时钟/利用率、VLA p99 延迟、队列深度、timeout 率。
- 保守模式：
  - 降低 VLA 调用频率（延长 plan 使用时间）；
  - 降低伺服频率/增益；
  - 暂停非必要站姿切换；
  - 批处理多端口请求；
  - 若提交时配置了低分辨率档，可在部署层切换；否则不改 `image_resize`。
- 如果 p99 > 阈值或 timeout 上升：进入 CONSERVE，优先保证已承诺 chunk 的合法性。

### 6.3 标定续航

- 头部双目：静态场景特征/桌面角点的重投影残差；极线一致性。
- 腕部：标定板/已知标记；或与头双目交叉验证。
- CUSUM：
  \[
  S_t=\max(0,S_{t-1}+(\kappa_t-\kappa_0-k)),\quad \text{alarm if }S_t>h.
  \]
- 告警动作：
  - 轻度：降低 IBVS 增益/只用 PBVS；
  - 中度：CALIBRATE（如果 API 允许/可离线校准后重启）；
  - 重度：关闭伺服，回退 VLA 开环；记录并请求人工。
- 标定置信度 \(\kappa_t=\exp(-\|\pi(\delta T,X)-u\|/\sigma_c)\)；没有对应点时用极线/立体一致性代理。

### 6.4 计划续航

- 视觉变化率 \(\dot d_t\)：光流/编辑分数/场景特征位移；
- 计划分歧 \(\delta_t\)：连续两次 VLA plan 的 EE 轨迹差（若异步请求）；
- 计划有效期：
  \[
  \hat T_{\text{plan}}=\frac{\nu_0}{\max(\epsilon,\dot d_t+\delta_t)}.
  \]
- 如果 \(\hat T_{\text{plan}}<H_c/f_c+\tau_{\text{RTT}}\)：请求重规划；否则用旧 plan + 伺服。
- \(\nu_0\) 离线标定；不要把它说成精确预测，只是调度启发式。

### 6.5 跨 trial 续航

- 记录每个 trial 的：成功、步骤分、时间、能量代理、p99、标定告警、站姿切换次数。
- 竞赛组合优先级：
  \[
  \text{priority}_t=\frac{q_t\Delta_t}{\text{cost}_t+\lambda_E E_t+\lambda_L L_t}.
  \]
- 工程预算：
  - Stage 1 指标-only 先上线；
  - Stage 2 Class A；
  - Stage 3 Class B；
  - 每阶段用单任务通道 A/B，不过门不推进。
- 热管理：正式评测前做 warm-up；多端口错峰/批处理；监控 p99；在提交配置允许的范围内降分辨率/降 VLA 频率。

## 7. 复杂度分析

| 组件 | 时间 | 空间 | 频率 |
|---|---|---|---|
| 指标更新 | O(d), d≈11 | O(d) | 每 chunk |
| 站姿查表 | O(1) 插值 | 预计算网格 | 每 chunk |
| A* 站姿规划 | O(E_s log N_s)，N_s≤10^3，E_s≤10^4 | O(N_s+E_s) | 触发时 |
| 模式选择 | O(|A|)=7 | O(1) | 每 chunk |
| 伺服 | O(k^3)，k≤20 | O(k^2) | 每 chunk |
| VLA | 摊销 1 次/30 步 | 6B 权重共享 | 异步 |
| CUSUM | O(d) | O(d) | 每 chunk |
| 总 CPU | <5ms/chunk | <100MB | 30Hz 下 <15% 单核 |

- 站姿图预计算离线；在线只查表和短路径。
- VLA 调用不增加；站姿触发时可能增加一次重规划，摊销到长任务可接受。
- 内存：图/网格/阈值 <100MB；指标日志 <1MB/320 trials。
- 结论：BUDGET-GAIT 的在线开销相对 167ms 执行块可忽略；主要成本是工程实现和离线标定。

## 8. 正确性论证

### 8.1 安全不变式

定义安全站姿集合

\[
\mathcal S=\{q:\sigma(q)\ge\sigma_{\min},\ \text{joint/collision OK},\ \text{camera view OK}\}.
\]

定义安全转移谓词 \(\mathrm{SafeTrans}(q,q')\)：

1. \(q\in\mathcal S\)，\(q'\in\mathcal S\)；
2. 转移时间 \(t_{\text{trans}}\) 满足 \(b^T\ge t_{\text{trans}}+t_{\text{stop}}+H_c/f_c\)（冷启动/同步 VLA 时再加 \(t_{\text{VLA}}\)；否则用异步缓存）；
3. 双臂在安全收拢位，接触残差 \(\epsilon<\epsilon_{\text{safe}}\)；
4. 转移速度/加速度在限幅内；
5. 转移路径无自碰撞/桌面碰撞。

**命题 1（安全保持）**：如果执行器只执行满足 \(\mathrm{SafeTrans}\) 的转移，且中止时返回上一安全站姿，则机器人始终停留在 \(\mathcal S\) 内，且不会超过时间预算。

证明草图：初始站姿安全；每次转移前后都在 \(\mathcal S\)；中止返回上一安全站姿（归纳假设）；时间不变式保证安全停止和至少一个执行块的余量。模型误差/外部扰动可能破坏前提，因此需要在线监控和保守裕度；命题是条件性的，不是无条件保证。

### 8.2 非回归性

**命题 2（名义非回归）**：如果当前站姿满足可达/扭矩/稳定约束，计划有效，且无编辑/标定告警，则 BUDGET-GAIT 的模式选择退化为 CHUNK-SERVO，不触发 STANCE；因此在理想名义条件下，其行为与第 12 轮一致。

证明草图：站姿触发条件为「可达赤字/扭矩赤字/保持功耗过高」；名义条件下均为假；安全过滤通过；模式选择在 PLAN/SERVO 之间，和 CHUNK-SERVO 相同。实际中可能因指标误报触发站姿，故需 G8/G9 控制误报。

### 8.3 预算可行性

**命题 3（时间可行）**：如果每次站姿转移前检查 \(b^T\ge t_{\text{trans}}+t_{\text{stop}}+H_c/f_c\)（同步调用时再加 \(t_{\text{VLA}}\)），则任务不会因站姿转移而超时；最坏情况可在 180s 前安全停止。

证明草图：时间预算单调递减；转移前预留转移+停止+一个 chunk；转移后仍有非负余量；归纳。能量/热预算用 TTE 约束：如果 \(\tau_i <\) 计划动作时长，则不执行高消耗动作，进入 CONSERVE/SAFE_HOLD。保守模式是否真的降低消耗需离线验证；否则命题退化为「不执行」。

### 8.4 指标校准

**命题 4（边际误报控制）**：在成功轨迹可交换的假设下，用成功校准集的 \((1-\alpha)\) 分位数作为阈值，新的成功轨迹的边际误报率 ≤ α。

证明：共形预测的标准结论；不保证条件误报/分布漂移下的性能。CUSUM 用于漂移检测，但没有共形保证；报告经验误报/检测延迟。

### 8.5 局限

- 安全/非回归/预算命题都依赖 URDF、相机标定、阈值和准静态假设；接触、变形、透明物体、外部人碰会破坏假设。
- 站姿净收益没有被证明，只是可证伪假设；G9 不过就砍掉。
- 能量代理不是真实电池；不能用于绝对续航声明，只能做相对调度。

| 站姿可达性 | URDF + 目标采样 | 可达裕度/可操作度提升 | G9 |
| 能量代理 | 台架/日志 | 代理 vs 实测功率相关性 | G9 |
| 标定漂移 | 合成扰动/换相机 | CUSUM 检测延迟/误报 | G10 |

### 9.2 仿真

- 任务族：
  1. 长距离/高扭矩：ToolboxStorage、StoreRacket、PackPhone；
  2. 插入/接触：PlugInEthernet、ArrangeTestTubes；
  3. 挂/叠：HangCup、StackBowls；
  4. 变形：FoldTowel（不应触发站姿）。
- 变量：站姿 off/Class A/Class B；指标门控 on/off；续航 on/off；预算紧/松；扰动（位置/遮挡/背景/人）。
- 指标：成功率、步骤分、时间、能量/成功、p99、站姿切换次数、恢复率、安全越界。
- 每组 ≥50 次；报告均值/CI；仿真只用于相对排序和稳定域，不预测真机绝对值。

## 10. 竞赛策略更新

### 10.1 分阶段投入

| 阶段 | 内容 | 风险 | 退出条件 |
|---|---|---|---|
| S0 | WLA + CHUNK-SERVO 基线 | 低 | 单任务跑通 |
| S1 | 指标-only 执行器（无站姿） | 低 | G8/G10 |
| S2 | Class A 腰/躯干站姿 | 中 | G9/G11 |
| S3 | Class B 微步态 | 高 | G9/G11 + pivot/重定位验证 |
| S4 | 全量 32×10 | 中 | G6/G10 |

**关键策略**：S1 是必做的安全增量；即使站姿失败，指标+续航仍然有价值。S2/S3 是可选增益，不能阻塞基线提交。

### 10.2 任务优先级

\[
\text{priority}_t=\frac{q_t\Delta_t}{\text{cost}_t+\lambda_E E_t+\lambda_L L_t}.
\]

- 先做长任务/远距离/高保持功耗任务：ToolboxStorage、StoreRacket、PackPhone、ArrangeTestTubes。
- 不做变形/小物件精细任务：FoldTowel、PackDoll、OrganizePencilCase（除非 G9 证明无回归）。
- 人为干扰轴：站姿切换期间遇人 → 暂停/恢复；不在这时切 base。
- 位置/背景/未见物品：站姿图按当前目标重算；Class B 需重定位。

### 10.3 提交节奏

- 若允许多次提交：先交 S1（安全基线+指标），再交 S2，最后 S3。
- 若只允许一次：S1+S2（如果 G9 过），不带 S3；保留回滚开关。
- 不在正式 320 trials 上做未验证的站姿 A/B。

## 11. 风险与合规

### 11.1 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 | 站姿/指标全离线，线上只有 VLA + 确定性控制器 | 最低 | 保守 |
| C2 | 站姿图/影子价格/模式选择都是确定性算法；阈值离线校准 | 低 | 主推 |
| C3 | 指标用 VLA 同一 checkpoint 的特征 | 低–中 | 需要强特征时 |

禁止：第二个学习策略/残差网络/独立视觉编码器/学习型成功预测器在线决策。指标阈值是统计校准，不是策略；站姿规划是图搜索，不是学习。

### 11.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 站姿净收益为负 | 时间/扰动成本 > 可达收益 | G9 门；只留指标+续航；Class A 优先 |
| `pivot` 语义不一致 | 站姿动作被拒/机器人不动 | 零 pivot 回退；单任务验证；Class B 禁用 |
| base 位移不可观测 | 目标系错，伺服追错 | Class A 优先；Class B 需视觉重定位；置信度低回退 |
| 相机运动/标定漂移 | 伺服退化 | 重定位/CUSUM/关 IBVS；站姿后强制重锚定 |
| 能量代理不准 | 续航调度错误 | 台架校准；只用相对排序；保守阈值 |
| 热/延迟模型不准 | CONSERVE 触发过早/过晚 | 在线监控 p99/温度；自适应阈值 |
| 指标误报 | 不必要站姿/重规划 | 共形阈值；CUSUM；G8 误报门 |
| 指标漏报 | 该换站姿没换 | 多指标融合；安全兜底；G9 |
| 站姿切换碰撞/失稳 | 安全风险 | 准静态、限速、收臂、稳定裕度、可中止 |
| 时间超支 | 180s 超时 | 时间不变式；站姿前检查；保守模式 |
| 单模型解释 | 被判第二个模型 | 确定性算法；离线阈值；材料写清 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复；320 trials SE≈2.4pp |

### 11.3 与第 12 轮方案的兼容与回滚

- 保留 CHUNK-SERVO 的全部接口；BUDGET-GAIT 是外挂执行器，可一键关闭。
- 回滚顺序：S3 → S2 → S1 → S0。
- 如果指标-only 仍不涨点（G8 失败），直接回 S0；不要为了「框架完整」保留无效模块。

## 13. 一句话押注

**用指标体系统一给时间、能量、热、标定和可达性定价，用离散站姿/微步态图只在净收益为正时改变身体，用 TTE/预算约束把 320 trials 的持续性能纳入决策；即使站姿收益不及预期，也能安全退化为一个预算感知的 CHUNK-SERVO。**

## 14. 本轮最大风险

最大风险是：桌面任务里站姿/微步态的净收益可能小于它引入的扰动、时间成本和 `pivot` 语义不确定性；如果 G9 在长任务上不涨点，就应把 BUDGET-GAIT 退化为「指标门控 + 续航预算」的轻量执行器，砍掉站姿层。
