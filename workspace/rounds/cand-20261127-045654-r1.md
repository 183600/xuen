## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（零样本泛化 → 未知物体不是「新类别」，而是「新可供性组合」）**
直觉：人第一次看到一个没见过的马克杯也能抓，不是因为「记住了这个杯子」，而是因为把它归约成了「圆柱、直径约 8cm、竖直轴、可从上方夹」。当前多数方案把零样本做成「外观最近邻检索」，但外观近邻未必可供性近邻：一个高瘦杯与一个矮胖碗在 CLIP 空间可能很近，抓法却相反。正确的零样本单位不是物体类别，而是**可供性等价类**：抓取宽度、抓取轴、接近方向、接触区域、所需间隙、支撑方式。只要训练分布覆盖了这些参数的组合，未见物体就不是零样本。**反直觉点：零样本的瓶颈是可供性覆盖，不是物体识别；检索外观只是代理，几何/功能等价类才是本体。**

**灵感 2（真实世界泛化 → 真正的敌人是「同语义、不同观测」的 nuisance 漂移）**
直觉：真机评测里，模型「不会做」和「会做但被相机/光照/帧率/延迟击穿」是两类完全不同的失分。手册明说评测跨**多台机器人**、多样场景、含人为干扰（F20），提交接口还要求 N 端口并发、隔离状态（F22），并记录时延抖动与动作统计（F23）。而训练数据是固定 rig 的 30fps rectified stereo（F25），评测却是两路高位相机、不同机器人外参、可能不同控制频率（F27）。这些漂移不改变任务语义，却系统性改变输入分布——它们应当被**中和**，而不是被更多数据「学会」。**反直觉点：真实世界泛化的大部分失分不是「不会」，而是「会但被 nuisance 击穿」；这类漂移的性价比最高的解法是校准与不变性，不是扩模型。**

**三者统一（本轮结论）**：语义零样本回答「未知物体怎么变成已知可供性」（I2/I9 扩覆盖），真实世界泛化回答「已知技能怎么在陌生观测下不崩」（I1/I11 中和 nuisance），而残余漂移需要被**检测并降级**而不是硬扛（I10）。三者相乘才是真机平均分。**本轮结论：第 2 轮押「数据引擎」仍对；但数据引擎的收益有一个乘数——部署时不被 nuisance 击穿。I11+I10 就是这个乘数。**

## 2. 形式化：把泛化误差拆成可下手的六项

设评测环境 \(e=(r,v,\tau,h)\)：机器人 \(r\)、视觉/场景 \(v\)、任务 \(\tau\)、人为干扰 \(h\)。观测 \(x=O_e(s)\)，策略 \(a=\pi(x)\)，动力学 \(s'=f_e(s,a)\)，单集得分 \(S(\pi;e)\)。真实世界泛化 gap：

\[
G(\pi)=\mathbb{E}_{e\sim D_{\text{eval}}}[S]-\mathbb{E}_{e\sim D_{\text{train}}}[S]
\approx G_{\text{sem}}(\tau)+G_{\text{obs}}(O_r)+G_{\text{dyn}}(f_r)+G_{\text{int}}(h)+G_{\text{ctl}}(T_a,\Delta t)+G_{\text{eval}}(\text{noise})
\]

| 误差项 | 物理含义 | 本轮主攻 |
|---|---|---|
| \(G_{\text{sem}}\) | 未见物体/指令的语义与可供性缺口 | I2 / I9 |
| \(G_{\text{obs}}\) | 相机 rig、光照、背景、帧率、观测 schema 漂移 | I1 / I11 |
| \(G_{\text{dyn}}\) | 摩擦、质量、夹爪柔顺、桌面高度差异 | I2 / I3 / I5 |
| \(G_{\text{int}}\) | 人为干扰、碰撞、遮挡 | I4 / I5 / I10 |
| \(G_{\text{ctl}}\) | chunk 固定、延迟与抖动、控制频率 | I4 / I6 / I10 |
| \(G_{\text{eval}}\) | 初始摆放、成功判定噪声 | I8 |

关键判断：\(G_{\text{obs}}\) 与 \(G_{\text{ctl}}\) 是**最便宜、且对 32 任务同时生效**的两项；\(G_{\text{sem}}\) 最显眼但最难。因此本轮新增点优先打在「中和 nuisance + 检测残余漂移」，而不是继续堆模型容量。

## 3. 对第 2 轮痛点的增量修订

- **P2 拆分**：P2a 语义零样本（未见物体/指令）；P2b 真实世界 nuisance（相机/光照/帧率/延迟）。两者解法不同，不能再用一个「泛化缺口」笼统对待。
- **P4（无触觉）补充**：腕部相机 + EE 位姿是比全局相机更 embodiment-invariant 的接触信号；I11 把它们作为不变锚点。
- **P5（时间压力）补充**：F21 确认按平均成功率排序、步骤分仅作平局；因此「检测-降级」保成功率优先于「冒险拿步骤分」。
- **P8（示教质量）维持**：数据侧仍要质量加权；但本轮不再扩数据点，只补接口对齐。
- **新增 P9（隐性真实世界漂移）**：多机器人外参、相机 rig 差异、观测 schema 缺键、30fps→评测帧率、时延抖动——这些不在官方 5 轴里，却在物理上存在（F20/F27）。
- **I4 修正**：`action_chunk_size` 在 metadata 固定、不能逐 episode 改（F24）。第 2 轮「自适应 chunk」若改 metadata 属违规；正确做法是**固定块长 + 块内有效视界 \(k\le T_a\)**，其余步填安全保持/制动动作。
- **I7 裁撤**：测试时世界模型前瞻延迟高、动作可控性未被证实，且与「低成本真实世界鲁棒」方向冲突；保留 WMA 资产转 I5 数据引擎。

## 4. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

- **Q9（可供性等价类）**：未见物体的零样本，用哪组可供性参数（宽度/轴/接近方向/接触区/间隙）表示最充分？检索先验与几何估计如何融合，误检索如何止损？
- **Q10（任务条件不变性）**：如何在不做在线权重更新的前提下，让表示对相机/光照/帧率不变，同时**不抹掉任务语义**（颜色在 ColorArrangement/FruitSorting 是信号，不是噪声）？不变性群如何由语言/任务门控？
- **Q11（残余漂移检测）**：如何用保形预测（conformal）给漂移分数定一个分布无关的误报上界，并把检测结果映射为「标称/谨慎/恢复」三档执行策略，使降级本身不引入新的分布假设？

## 5. 设计原则（新增 PR6–PR8）

- **PR6 先中和 nuisance，再扩容量**：能在推理期用校准/归一化/不变表示消掉的漂移，不要用更大模型去拟合。
- **PR7 检测-降级优先于硬扛**：不确定时缩短有效视界、放慢、重观测、回退；保成功率优先于冒险拿步骤分。
- **PR8 任务条件不变性**：不变性不是全局的；颜色、纹理、形状哪些是信号由任务/指令决定，门控错误比不做不变性更伤。
- PR1–PR5 保留（第 2 轮 §4）。

**一句话**：I11 的「任务条件不变性」若门控错误，会把 ColorArrangement/FruitSorting 的颜色信号当噪声抹掉；I10 的保形阈值若在真实多机器人上因分布非交换而失效，会频繁误报、拖慢标称任务——**最大风险不是漂移本身，而是「不变性/检测」引入了新的分布假设且未被 L0 及时证伪。**

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2）

> 检索日期：2026-11-26（第 1 轮）、2026-11-27（第 2–3 轮）；来源见 §6。承接 v1.1：深化 I1/I9，修正 I4，裁撤 I7 推理路径，新增 I10/I11；I2/I3/I5/I6/I8 维持并做接口对齐。清单只增改不重置。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I1 v3 考纲校准 + 评测管线匹配增广引擎 ★★★★★
- **动机**：官方 5 类泛化轴之外，真机评测还存在相机 rig、光照、压缩、帧率、时延、机器人本体的隐性漂移（F20/F27）；这类漂移对 32 任务同时生效，是最便宜的全局增益。
- **本轮深化（真实世界泛化）**：在第 2 轮「考纲卡」之上加一层「管线卡」——把训练数据回放通过一个**评测管线模拟器**：30fps→目标控制帧率重采样、AV1/JPEG 压缩、曝光/白平衡/伽马/色相扰动、运动模糊与噪声、相机外参抖动与裁剪缩放、观测延迟、关节零位与夹爪标定偏差、桌面高度 ±2cm。增广轴按「是否改变任务语义」门控（PR8）：ColorArrangement/FruitSorting 不做色相/白平衡增广，只做曝光与传感器噪声。
- **与现有方案差异**：直接 SFT 用标称数据；第 2 轮盲增广/考纲增广只覆盖官方 5 轴；本点把**评测管线本身**作为增广对象，并同时产出 I11 所需的「干净-扰动」成对视图。
- **技术可行性**：高。图像/时序扰动是纯数据工程；成对视图训练只增加一次前向。唯一需核实的是评测真实帧率与外参，未公开部分按 15Hz/±5° 设保守范围。
- **所需资源**：1×24GB GPU（官方默认微调，F11）；增广输出约 2TB；1 人周工程。
- **落地步骤**：①实现管线模拟器（图像/时序/本体三组）；②每任务管线卡 + 语义门控表；③成对视图离线生成；④L0 剂量-响应；⑤与 I11 联合训练；⑥L1 析因筛主效应。
- **风险**：过度增广破坏任务语义（缓解：语义门控 + 每轴 L0 上限）；模拟管线与真实评测仍有偏差（缓解：单任务通道抽测校准 + I8 注册表记录「离线增益→真机增益」）。

### I2 v2.1 数据引擎 2.0：110 语料孪生迁移 + 加权共训 + 评测 schema 对齐 ★★★★★
- **动机**：单模型平均分被最弱任务支配（P1）；示教语料与质量双重浪费（P8）；训练/评测观测 schema 不一致会静默丢信息（F27）。
- **本轮深化（接口对齐）**：在三件事（孪生语料入训、loader 加权 patch、示教质量加权）之外新增：
  1. **只用评测可用键**训练：评测没有 `state_torso`/`state_d435`/双腿键（F27），训练时不得依赖；EE 位姿统一用 `*_ee_pose_gripper_base`。
  2. **相机 rig 映射**：训练 `head_stereo_left/right`（rectified）→ 评测 `cam_left_high/cam_right_high` 的视角/裁剪对齐；无法精确映射时用 I1 的外参抖动增广覆盖。
  3. **帧率对齐**：训练 30fps（F25）→ 评测控制频率未知，按 15Hz 参照做 2× 降采样与随机丢帧，避免时间尺度错配。
- **与现有方案差异**：均匀混训 + 直接喂原始键；本点先做 schema/rig/fps 对齐，再做孪生加权，避免「数据越多、错配越大」。

## 1. 形式化推导

### 1.1 泛化误差分解与创新点映射

沿用第 3 轮想法区 §2：
\[
G(\pi)\approx G_{\text{sem}}+G_{\text{obs}}+G_{\text{dyn}}+G_{\text{int}}+G_{\text{ctl}}+G_{\text{eval}}
\]
映射：\(G_{\text{sem}}\)→I2/I9；\(G_{\text{obs}}\)→I1/I11；\(G_{\text{dyn}}\)→I2/I3/I5；\(G_{\text{int}}\)→I4/I5/I10；\(G_{\text{ctl}}\)→I4/I6/I10；\(G_{\text{eval}}\)→I8。关键性质：\(G_{\text{obs}}\) 与 \(G_{\text{ctl}}\) 对 32 任务同时生效，单位算力的期望收益最高，故 I1/I11/I10 优先级上调。

### 1.2 零样本 = 可供性等价类

设物体 \(o\) 的可供性 \(a(o)\in\mathcal{A}\)，训练覆盖 \(\hat{\mathcal{A}}_{\text{train}}\)。未见类别 \(c\notin\mathcal{C}_{\text{train}}\) 的失败概率上界：
\[
P_{\text{fail}}(\pi\mid c)\le \underbrace{P(a(o)\notin\hat{\mathcal{A}}_{\text{train}})}_{\text{覆盖缺口}}+ \underbrace{P(\pi\text{ fails}\mid a\in\hat{\mathcal{A}}_{\text{train}})}_{\text{执行缺口}}
\]
I2/I9 降低第一项；I1/I11 降低第二项。若检索给出 \(\hat a\) 且几何核验满足 \(\|\hat a-a\|\le\delta\)，则第一项退化为检索/几何误差。**推论：零样本数据配比应按可供性参数空间分层，而不是按物体类别分层。**

### 1.3 不变性上界

设 \(\Phi\) 对 nuisance 群 \(G\) 是 \(\varepsilon\)-不变：\(\sup_{g\in G}\|\Phi(gx)-\Phi(x)\|\le\varepsilon\)。若策略对 \(\Phi\) 是 \(L\)-Lipschitz，则
\[
|S(\pi;gx)-S(\pi;x)|\le L\varepsilon
\]
训练最小化 \(\mathcal{L}_{\text{inv}}\) 即压低 \(\varepsilon\)。但 \(G\) 不能取全局：颜色在 ColorArrangement 是信号，取 \(G_\tau\) 由语言/任务门控（PR8）。**推论：不变性损失必须与任务条件联合训练，否则会把判别信号当噪声压掉。**

### 1.4 保形漂移检测

标称校准分数 \(s_1,\dots,s_n\)，新分数 \(s_t\)，保形 p 值 \(p_t=(1+\#\{s_i\ge s_t\})/(n+1)\)。交换性下 \(P(p_t\le\alpha)\le\alpha\)。真实漂移破坏交换性，故：
- 只用它做**相对**触发（同一机器人/同一时段内），不做跨域绝对保证；
- 在 I8 注册表中记录每个机器人/光照条件的误报率，滚动重估 \(\alpha\)；
- 与「动作方差」快信号取或，降低检测延迟。

### 2.2 I10 漂移哨兵 + 三档降级

```python
class ShiftSentinel:
    def __init__(self, calib_scores, alpha=0.05):
        self.calib = sorted(calib_scores)
        self.alpha = alpha

    def score(self, obs, z, a_chunk, fwd=None):
        s_vis = 1 - cosine(z, self.ref)
        s_photo = photometric_shift(obs)          # 曝光/直方图/模糊
        s_act = action_uncertainty(a_chunk)        # K 采样方差或块内一致性
        s_dyn = fwd.one_step_error(obs) if fwd else 0.0
        return 0.4*s_vis + 0.2*s_photo + 0.3*s_act + 0.1*s_dyn

    def pvalue(self, s):
        return (1 + sum(c >= s for c in self.calib)) / (len(self.calib) + 1)

    def mode(self, obs, z, a_chunk):
        p = self.pvalue(self.score(obs, z, a_chunk))
        if p >= self.alpha:      return "NOMINAL"
        if p >= self.alpha / 4:  return "CAUTION"
        return "RECOVER"

# 执行层（与 I4/I6 共用）
def execute(obs, policy, sentinel, T_a):

    if conf > TAU_HIGH:      a = geo
    elif conf < TAU_LOW:     a = prior.mean
    else:                    a = bayes_update(prior, geo, conf)
    return a if a.conf > TAU_ACCEPT else None     # None -> 保守顶抓
```

### 2.4 I1 管线匹配增广（与 I11 共享成对视图）

```python
PIPELINE = [
    ("photo",   [exposure, white_balance, gamma, hue], 0.5, gate=not_color_signal),
    ("sensor",  [blur, noise, av1_jpeg],               0.3, gate=always),
    ("camera",  [extrinsic_jitter, crop, resize],       0.3, gate=always),
    ("temporal",[fps_resample, frame_drop, delay],      0.3, gate=always),
    ("embodiment",[joint_offset, gripper_calib, table_h],0.2, gate=always),
]

def augment_episode(ep, card, rng):
    views = [ep]
    for axis, fns, p, gate in PIPELINE:
        if rng.random() < p and gate(ep.task):
            dose = sample_dose(card, axis)        # 考纲卡 + 管线卡
            ep = apply_axis(ep, axis, dose)
            views.append(ep)                      # 成对视图给 I11
    return ep, views
```
