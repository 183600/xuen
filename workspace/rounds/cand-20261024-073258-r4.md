# 第 8 轮 · SAFE-PILOT：30% 天花板是接触与覆盖问题，不是模型类别问题

> 检索/复核日期：2026-10-24（UTC）。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「避障控制」「多语言支持」「数据集」。先说结论：**这一轮我不再把“换更大的 VLA / 世界模型”当主押注，也不押“多模型路由”。榜单头部三个架构（VLA、4B VLA、14B 世界动作模型）在统计上打平；步骤分差不是“终局失败”的证据；任务路由收缩后只值 +2.15pp。真正卡住 30% 的是两件事：接触密集的终端操作（插入、拧盖、拉链、堆叠）和五轴评测的覆盖缺口。对应的主押注是：一个确定性的、接触感知的立体安全漏斗（CASF）+ 一个立体一致的轴因子数据引擎（SCA）；多语言只做便宜的保险（LCSA），不做主轴。**

## 0. 本轮先核实：六个新事实

### 0.1 规则：成功率第一，5 轴×2，单模型，180s

中文手册 §1.2 与英文手册写得很清楚（[S3][S4]）：

> 实时榜单按 32 个任务的 **总平均成功率** 排序；成功率相同时按 **总平均步骤分** 排序；若仍相同，则 **提交日期较早** 的模型靠前。

同一页还给出评测结构：32 个任务，每任务 **10 次独立运行**，包含 **5 种泛化类型、每种 2 次**；单次真机执行上限 **180 秒**；所有任务必须用 **同一个模型** 完成，不得混合多个模型；模型类型不限（World Model、VLA 均可）；选手自部署，官方通过远程 API 调用；另有 **不计分单任务调试通道**（[S3][S4]）。

这修正了第 7 轮的一个隐含假设。第 7 轮把“成功率 + 步骤分”当成综合目标，于是“只涨步骤分”的工作也被认为有价值。新规则下，**步骤分只是并列裁决**；只涨步骤分、不涨成功率的组件，价值接近零。CASF 和 SCA 都必须以 **成功率** 为主指标，步骤分只作为稠密训练信号和并列保险。

### 0.3 统计：top-3 在噪声内；步骤分差是部分分产物；任务路由收缩后 +2.15pp

我把 8×32 的 `task_metrics` 全部复算了一遍（[S6]）：

- 8 模型总平均成功率 **25.18%**，总平均步骤分 **33.76%**，平均差 **+8.59pp**。
- 模型级“成功率 vs 步骤分”相关系数 **0.991**；任务级均值相关 **0.9999**；“步骤分差 vs 成功率”相关 **0.870**。
- 前三名差距：29.7−28.5=**1.2pp**，29.7−27.9=**1.8pp**，28.5−27.9=**0.6pp**。320 trials 在 p≈0.25 时的标准误约 **2.4–2.6pp**，所以 **前三名统计上打平**。
- 每任务只有 10 trials，p≈0.25 时任务级标准误约 **13.7pp**；逐任务排名极不稳定。逐任务跨模型成功率极差平均 **17.93pp**（最小 7.95，最大 29.4）。

**步骤分差不是“终局失败”的证据。** 设步骤分 \(s=\sum_i w_i p_i\)、成功率 \(p=\prod_i p_i\)。只要模型在某几步上完成、在后续步骤失败，就会出现 \(s>p\)；这个差值是部分分结构的算术结果，且会随整体能力同向变化。观测到的 0.87/0.9999 相关正说明它主要被整体能力解释，而不是独立地指出“最后一步”。第 7 轮把它当成“失败集中在后段”的强证据，是本轮要修剪的过度推断。**要定位失败，必须用单任务调试通道收集逐步成功/视频，而不是从聚合分差反推。**

**任务路由不值得做。** 逐任务取 8 个模型的最优值，原始 oracle 为 **33.96%**，比最好单模型 29.7% 高 **+4.26pp**；但每任务只有 10 trials，最大值有向上偏差。用启发式经验贝叶斯收缩（n=10, k=5）后，oracle 降到 **31.85%**，只比最好单模型高 **+2.15pp**（量级判断，不是精确估计）。再叠加“单模型、不得混合多个模型”的规则，以及学习型 router 的复杂度，这条路不值得作为主轴。

### 0.4 数据集：32k–33.3k episodes、169h、811GB、四路相机、head stereo 已校正

官方挑战页写 32 个任务、**32,000 demonstrations、169 hours**（[S2]）。Kinetic Blocks 的统计更细：**33,276 episodes、18,282,246 frames、169h、32 repos、811GB、LeRobot v3.0、30fps、480×640、4 路相机**（[S11]）。HangCup 数据卡实测（[S10]）：

- 相机：`head_stereo_left` / `head_stereo_right`（**rectified**）+ `wrist_left` / `wrist_right`。
- 状态：双臂关节、夹爪、`lower_body`、`state_torso`、**`state_d435`（D435 相机位姿）**、EE 位姿 **base 与 torso 两套坐标**。
- 动作：关节、EE 位姿、`action_d435`、`base_command`、`pivot` 等。
- 指令：每任务 **5 条英文复述**（`meta/tasks.parquet`，[S4]）。
- 许可：HF 数据卡 `license: apache-2.0`（[S10]）。

这意味着两件事。第一，**立体几何在离线数据里是可用的**：左右目已校正，`state_d435` 给了相机位姿，EE 位姿有两套坐标，足以做 3D 重建、遮挡推理和碰撞检查。第二，数据虽然大，但从数据卡/采集设置推断，演示主要来自同一套 G1/桌面/光照/背景；评测的五个轴里，**位置轴**在演示中有变化，**背景/干扰物/未见物品/人为干扰**在演示中并没有系统覆盖。数据集的缺口不是“量”，而是“轴”。

### 0.5 接口：v2 支持双目高位相机、EE 动作、自定义观测裁剪

当前 GitHub main 的最新提交是 `edd0a1c9`（2026-08-21，v2），README 用 `obs_delta_indices` + `image_resize` + `action_chunk_size`（[S8]）。观测包含 4 路 RGB、双臂关节/EE、夹爪、下半身、单字符串 `observation.language`；动作空间 joint / ee 二选一；`reset()` 每 episode 一次。搜索结果里还出现过一个带 `data_keys` / `obs_chunk_size` 的新版说明，但不在当前 main 提交中，我标为 **未核实**，提交前必须复核。

对本轮最重要的是：API 同时暴露 **`cam_left_high` / `cam_right_high`**（左右高位相机）。结合数据集的 `head_stereo_left/right`（rectified）和 G1 头部 D435i（[S28][S29]），这两个视角 **很可能就是同一对立体相机**；但 API 是否保持校正、分辨率/压缩是否改变内参，需要实测标定。若成立，我们就能在不引入第二个学习模型的前提下，用经典立体匹配得到度量深度。这是 CASF 的物理基础。

### 0.6 文献：安全过滤已经从“仿真”走到“真机 + 动态障碍”，但没人做“接触许可”

本轮补读了 2026 年的安全过滤工作（[S15]–[S23]）：

- **Attention-Guided Safety Filter**（arXiv 2606.09749）：training-free，用 VLA 的注意力头定位目标，CBF 过滤，动态障碍场景比 oracle 高 **43%**。说明“目标定位”不一定需要第二个模型。
- **WBAG**（arXiv 2610.01083）：全身 + **附着物体几何**，RGB-D，CBF；场景安全 **97.38%**，安全成功率 **59.38%**。
- **Multi-Link Safety Filtering**（arXiv 2609.40007）：5 个椭球、RGB-D、光流，CPU **2.2ms**；SO-101 上碰撞率 **65.6%→27.3%**，安全成功率 **29.4%→50.4%**。
- **VLPSA**（arXiv 2609.22462）：Poisson 安全函数，全身 + 抓取物，碰撞避免 **23.1%→91.2%**，真机 Franka，含动态障碍与人类。
- **AEGIS/VLSA**（arXiv 2512.11891）：plug-and-play CBF，避障提升 **>50%**，任务成功率 **+10%**。
- **SafeLoop**（arXiv 2609.26313）：风险感知回滚，危险降低 **70%**。
- 还有 CoFreeVLA（arXiv 2601.21712，双臂自碰撞）、Neuro-symbolic safety（arXiv 2607.01378，82.8% 避碰 / 81.6% 成功）、SafeHarness（arXiv 2609.20822，81.2% 成功 / 91.9% 避碰）。

这些结果说明：**确定性安全层在真机上确实能把碰撞率打下来，并且常常顺带提升任务成功率**。但它们有一个共同的默认：环境里的非目标物体都是障碍，目标也尽量别碰。对 UniBot 的插入、拧盖、拉链、堆叠，这个默认是错的——**该接触的时候必须接触**。现有工作里最接近的是 WBAG/VLPSA 的“附着物体几何”，但它们仍然把环境当障碍，没有把“目标接触”做成一个 **步骤条件化的许可模式**。这是本轮的 research gap。

多语言方面（[S24]–[S27]）：

- **Beyond English**（arXiv 2606.15714）：VLA 在非英语指令上显著掉点，且伴随表征漂移。
- **When Does Language Matter**（arXiv 2606.11906）：语言的影响随步骤非均匀，某些步骤语言关键、某些步骤几乎无关。
- **LangGap**（arXiv 2603.00592）：不少 VLA 实际上会忽略语言，视觉 grounding 才是主因。
- **Greek transfer**（arXiv 2609.07470）：跨语言迁移可行，但需要对齐。

结论：多语言是一个 **真实的、但可能不触发** 的风险。规则/数据/站点都是中英双语，评测语言未写死；如果评测用中文，头部英文模型可能掉点；如果只用英文，投入就是浪费。正确做法不是把它当主轴，而是做一次便宜的审计，再决定是否加 LCSA。

## 1. 三个灵感词，各自钉到事实上

### 1.1 避障控制：不是“躲开一切”，而是“该接触时接触、该躲时躲”

UniBot 的五轴里有 **干扰物** 和 **人为干扰** 两轴，安全过滤天然相关。但直接把一个标准 CBF 套上去，会遇到一个矛盾：

- 标准 CBF 把目标也当障碍（或至少保持安全距离），于是 **插头插不进插座、碗叠不到碗上、拉链拉不上**。
- 如果为了任务成功把安全距离调到 0，过滤器又挡不住真正的附带碰撞（撞倒旁边的杯子、碰到人的手、把容器推下桌）。

本轮的解法是把“目标/障碍”的边界做成 **步骤条件化** 的：

| 步骤相位 | 目标物体 | 其他物体 | 安全策略 |
|---|---|---|---|
| 接近 | 仍是障碍（保持 5cm） | 障碍 | 标准 CBF |
| 对齐 | 允许进入接近锥 | 障碍 | 接触锥 + 侧向约束 |
| 插入/操作 | 允许接触目标端口/表面 | 障碍 | 轴向约束 + 力/深度监控 |
| 操纵 | 允许持续接触 | 保护容器/桌面 | 支撑多边形 + 防倾倒 |
| 撤退 | 重新变回障碍 | 障碍 | 反向 CBF |

这就是 **Contact-Aware Safety Funnel（CASF）**：一个确定性的、training-free 的、单模型兼容的包装层。它的新意不在 CBF 本身，而在 **“接触许可”是步骤和任务语义的函数**，而不是一个全局的安全距离。SSG 给出当前步骤；任务规范给出目标/容器；立体几何给出距离；CBF-QP 给出安全动作。四者缺一不可。

为什么可行？因为 UniBot 的步骤是官方公开的（第 7 轮已抓全 32 任务的 `score_steps`），任务的目标物体是已知的，头部双目已校正，EE 动作空间让 rollback 很容易。CASF 不需要重新训练策略，也不需要第二个策略模型；它只改动作，不改权重。这在“单模型、不得混合”的规则下是合规的。

### 1.2 数据集：不是“更多数据”，而是“补五轴覆盖”

官方数据 33k 条、169 小时，听起来很多；但评测是 **5 轴分布偏移**。数据集里的变化主要是物体摆放位置；背景、干扰物、未见物品、人为干扰在演示中没有系统出现。继续堆同分布数据，边际收益很低；真正缺的是 **轴覆盖**。

naive 的 2D 增强（换背景、贴贴纸、CutMix）会破坏几何：腕部视角和头部视角对不上，深度对不上，动作标签也对不上。于是我们提出 **Stereo-Consistent Axis Augmentation（SCA）**：

1. 用已校正的双目 + `state_d435` + EE 位姿，把每条 episode 重建成 3D 场景（桌面平面、物体掩码、6D 位姿、相机位姿）。
2. 按五轴做 **3D 编辑**：平移目标/容器（位置轴）、插入官方场景里的其他物体（干扰物轴）、替换桌面/背景纹理（背景轴）、用相似 affordance 的物体替换目标（未见物品轴）、按官方 `human_1_note` / `human_4_note` 做 1-DOF 平移或撤销（人为干扰轴）。
3. 用同一 3D 场景渲染左右目，检查视差/极线一致性；不一致的样本直接丢弃。
4. 对动作做 **重定向**：背景编辑不改动作；位置编辑用桌面系刚体变换重定向接近/放置段；干扰物/未见物品/人为干扰用 CASF 或 NRB 生成避障/恢复动作。
5. 用 **Coverage Cartography（CCM）** 统计每个任务在五轴上的覆盖，优先补洞，而不是盲目加量。

这比“再采 10 万条”便宜，也比 2D 增强更保真。它直接对应“数据集”这个灵感词：**数据的价值在覆盖，不在体积。**

### 1.3 多语言：不是主押注，是便宜的保险

规则、数据、站点都是中英双语，但评测指令的语言没有写死。数据集里每条任务是 5 条 **英文** 复述；站点上有中文任务描述；API 的 `observation.language` 是单字符串。三种可能：

1. 评测只用英文 → 多语言投入为 0。
2. 评测用中文 → 英文中心的 VLA 可能掉点；文献显示非英语会显著退化（[S24]）。
3. 评测用中英混合/未见复述 → 需要语言鲁棒性，但不一定要完整的多语言训练。

所以本轮不把多语言当主轴，而是做 **Language-Critical Step Alignment（LCSA）** 的保险：

- 先把 32×5 条指令翻成中文（官方中文描述 + LLM 复述 + 人工校验），做一次 **语言审计**：8 个任务 × 5 次，英文 vs 中文。
- 如果中文掉点 <5pp：跳过，不加模块。
- 如果掉点 5–10pp：只做翻译增强（把中文指令混入训练），不改结构。
- 如果掉点 >10pp：启用 LCSA——只在对语言敏感的步骤（目标选择、空间关系、属性）做跨语言表征对齐（MPCA 风格），动作专家冻结。

这符合“When Does Language Matter”的结论：语言影响是步骤非均匀的（[S25]）；也符合 LangGap 的警告：不要假设 VLA 一定在用语言（[S26]）。**先测，再投。**

## 2. 主判断：30% 是接触与覆盖问题

### 2.1 头部架构分散，但统计上打平

预览榜前三名是三种不同的路线：

- **MolmoAct2**：action reasoning VLA，深度感知感知 token + 可编辑轨迹 trace，7B，强调空间推理（[S12]）。
- **WALL-OSS-0.5**：4B VLA，3B VLM 主干 + 离散动作/多模态/flow matching 三目标，20+ 本体，15Hz（[S13]）。
- **DreamZero**：14B World Action Model，视频扩散联合预测世界与动作，7Hz，强调泛化（[S14]）。

它们的规模、范式、训练目标都不同，但差距只有 **1.2–1.8pp**，小于 320 trials 的标准误。**如果预览榜反映真实评测，这说明瓶颈不在模型类别或参数量。** 继续换更大的模型，边际收益很可能不如把接触和覆盖做好。这是本轮最重要的判断，也是把预算从“换模型”转向“加安全层 + 补数据轴”的依据。

### 2.2 最难的任务是接触密集的

逐任务平均成功率（8 模型）最低的是（[S6]）：

| 任务 | 平均成功率 | 类型 |
|---|---:|---|
| Plug In Ethernet | 17.7 | 插入 |
| Unlock | 20.1 | 精密 |
| Spell robot | 21.8 | 放置 |
| Organize Stationery | 22.5 | 插入/整理 |
| Open Pill Bottle | 22.7 | 拧盖 |
| Hang the Cup | 23.0 | 挂 |
| Pick Out Battery | 23.3 | 取出 |
| Zip Up | 23.4 | 变形 |

最高的是 Stack Cups 30.3、Conveyor Food Sorting 29.1、Place Photo Frames 28.0、Paper Cup Stacking 28.0。**接触密集任务在底部过度代表**：插入、拧盖、拉链、挂、精密取出。相反，简单的放置/分拣/堆叠在顶部。这个模式支持“接触是瓶颈”，但不是决定性的：Spell robot 是放置却也很难，Stack Cups 是堆叠却相对容易；每任务 10 trials 的噪声也很大。稳妥的结论是：**接触密集任务是高杠杆的近失误来源，而不是说所有放置都已解决。**

### 2.3 步骤分差不能定位失败

第 7 轮把“步骤分 − 成功率 ≈ +8.6pp”当成“失败集中在最后一步”的证据。本轮复算后，这个推断不成立：

- 8 模型平均成功率 25.18%，平均步骤分 33.76%，差 8.59pp。
- 模型级相关 0.991，任务级 0.9999；差与成功率的相关 0.870。
- 这是部分分结构的必然结果：只要模型完成了部分步骤，步骤分就会高于全完成成功率。它不告诉你失败发生在第 1 步还是最后 1 步。

**修剪：** 不再从聚合分差推断失败位置；改用单任务调试通道的逐步视频/谓词日志。这个“失败定位审计”本身是一个低成本、高信息量的流程创新。

### 2.4 任务路由不值得

原始逐任务 oracle 33.96%（+4.26pp）看起来诱人，但：

- 每任务只有 10 trials，最大值向上偏差；收缩后 31.85%（+2.15pp）。
- 规则明确禁止混合多个模型；router 要么是第二个模型，要么是一个多 head 的单模型，复杂度高。
- 前三名统计上打平，router 要学的“谁在哪个任务更强”本身就在噪声里。

**修剪：** 不做 task-conditioned expert routing / MoE。把这份预算给 CASF 和 SCA。

### 2.5 数据集的缺口是轴，不是量

从数据卡/采集设置推断，官方数据主要是单一实验室的 32 任务演示；评测是五轴分布偏移。位置轴在演示中有变化，其他四轴在演示中没有系统覆盖。继续加同分布数据，不能补背景/干扰物/未见物品/人为干扰。SCA 和 CCM 就是针对这个缺口；L2L（外部实验室数据）是赛后选项，因为外部数据政策未确认，默认 OFF。

## 3. 方案轮廓：SAFE-PILOT

### 3.1 CASF：接触感知的立体安全漏斗

```text
obs（4 RGB + proprio）
  → 双目校正 + SGBM 深度 + 点云
  → 桌面平面 RANSAC + 物体聚类 + 椭球/胶囊拟合
  → SSG 当前步骤 + 任务规范 → 目标/障碍分解
  → 接触模式（APPROACH / ALIGN / INSERT / MANIPULATE / RETREAT）
  → CBF-QP（目标接触锥 + 非目标障碍 + 自碰撞 + 关节限位）
  → 安全动作 chunk → 执行
  → 谓词/距离监控 → 不可行/丢失接触 → rollback + 重查询
```

关键点：

- **目标/障碍是步骤的函数**，不是全局常量。
- **接触锥**允许目标接触，但限制接近方向；非目标物体保持安全距离。
- **附着物体几何**（手里拿的插头/碗/拉链头）参与碰撞检查，避免“机器人没撞，但手里的东西撞了”。
- **回滚**保存最后安全 EE 位姿；CBF 不可行或谓词从 1→0 时撤退、重观测、重查询。
- **单模型合规**：不训练第二个策略；立体匹配、点云、RANSAC、CBF 都是确定性代码。若用 SAM2 做掩码，它是感知模块，需披露；默认用颜色/几何/任务先验，避免争议。

预期：干扰物/人为干扰轴上碰撞率显著下降，近失误转成功；整体 +1–3pp；干净场景不回归。若干净场景回归 >2pp，按任务关闭 CASF。

### 3.2 SCA：立体一致的轴因子数据引擎

分阶段，先做高 ROI 的背景/位置，再做干扰物/未见物品/人为干扰：

| 阶段 | 编辑 | 动作标签 | 难度 | 优先级 |
|---|---|---|---|---|
| 1 | 桌面/背景纹理替换 | 不变 | 低 | 高 |
| 2 | 目标/容器平移 | 桌面系刚体变换重定向 | 中 | 高 |
| 3 | 插入官方场景物体作干扰 | CASF 生成避障/重定向 | 中 | 中 |
| 4 | 相似 affordance 物体替换 | 抓取位姿迁移 + 轨迹调整 | 高 | 中 |
| 5 | 官方 human 备注回放 | NRB 恢复动作 | 高 | 中 |

每个样本过 **立体一致性校验**：左右目同一 3D 场景渲染，视差/极线误差超阈值就丢弃；再用 domain discriminator 检查真实感。动作标签用仿真回放或人工抽检验证。数据量：32k 的 20% × 5 种编辑 ≈ 32k 增强样本；8×H100、2–3 周、约 5TB。若资源有限，只做 8 个接触密集任务 + 阶段 1–2。

预期：背景/位置/干扰物轴 +2–5pp，整体 +1–3pp；比 2D 增强更保真。风险：sim-to-real gap、外部资产许可、动作标签有效性；用官方场景物体、默认不用外部数据、严格校验。

### 3.3 LCSA：语言关键步对齐（保险）

先审计，再决定：

- 32×5 条中文指令；8 任务 ×5 次英文 vs 中文。
- 掉点 <5pp：跳过。
- 5–10pp：翻译增强。
- >10pp：LCSA（只对齐语言关键步；MPCA 风格；动作专家冻结）。

预期：英文评测下为 0；中文评测下 +5–15pp。风险：翻译伪影、评测语言未知；用官方中文描述 + 人工校验。

### 3.4 保留 / 升级 / 修剪

| 关系 | 内容 |
|---|---|
| 保留 | SSG（评分步骤图）、PGL（放置目标阶梯）、OPT（少样本位姿统计）、SVL（落点闭环）、NRB（官方备注恢复库）、GPR-VLA + WLA 底座、TLE/ACP/GF、DebugLoop |
| 升级 | SSG → **SSG-2**（接触模式 + 恢复边）；SVL → **SVL-2**（接触感知终端伺服）；NRB → **HSP**（备注→扰动/恢复程序） |
| 新增 | **CASF**（主押注）、**SCA**（主押注）、**CCM**（覆盖制图）、**LCSA**（保险） |
| 降级 | ICR（可选增强）、L2L（外部数据政策未确认，转赛后）、TCLB（离线比较） |
| 修剪 | 任务路由/MoE；从步骤分差推断终局失败；多语言当主轴；“更多数据量”；FLEET 作为研究轴（保留为工程检查单） |

## 4. 与第 7 轮的关系

第 7 轮的 PILOT 把“终局放置”作为闸门，这个方向仍然成立；本轮把它 **细化为“接触密集的终端操作”**，并把“安全”从隐含前提变成显式模块。第 7 轮的三个过度推断本轮修剪：

1. **步骤分差 → 终局失败**：不成立，是部分分产物。
2. **多模型/任务路由**：收缩后 +2.15pp，且违规，砍。
3. **放置优先 = 只做放置**：不对；插入、拧盖、拉链、挂、取出都是接触密集，CASF 覆盖它们。

同时保留第 7 轮真正有价值的东西：官方步骤图、放置位姿统计、落点闭环、官方 human 备注、单模型底座、数据引擎。这样第 8 轮不是推倒重来，而是 **把目标函数改对、把证据标准改严、把预算放到接触与覆盖上**。

## 5. 一句话押注

**30% 不是模型不够大，而是接触与覆盖不够；用确定性的接触感知安全漏斗把近失误变成成功，用立体一致的数据引擎补五轴覆盖；多语言只做保险，不做主轴。**

## 1. 事实核对（本轮新增，全部一手；来源表见 §11）

### 1.1 排名与评测协议：成功率优先，步骤分只是并列裁决

中文手册 §1.2 原文（[S3]）：

> 实时榜单按 32 个任务的 **总平均成功率** 进行排序，成功率相同时按 **总平均步骤分** 排序，若仍相同，则 **提交日期较早** 的模型排序靠前。

英文手册（[S4]）同样明确：

> The real-time leaderboard is sorted by overall average success rate across all 32 tasks. In the event of a tie, the overall average step score is used as the differentiator. If still tied, earlier submission dates rank higher.

同页给出评测结构（[S3][S4]）：

- 32 个标准化桌面任务，覆盖抓取、放置、双手协作。
- 每任务 **10 次独立运行**，包含 **5 种泛化类型、每种 2 次**：位置、干扰物、桌面背景、未见物品、人为干扰。
- 单次真机执行上限 **180 秒**；超时记失败，并按执行情况计算步骤分。
- 所有任务必须用 **同一个模型** 完成，不得混合多个模型；模型类型不限（World Model、VLA 均可）。
- 选手自部署，官方通过远程 API 调用；官方不托管模型、不提供推理算力。
- 另有 **不计分单任务测试通道**，结果不进排行榜。

**页面文案与手册的冲突**：`leaderboard.html` 的说明写的是“按平均成功率与步骤分综合排序”（[S5]）。但手册 §1.2 是更具体、可操作的规则。本报告以手册为准，并把“向官方确认排名口径”列为开放问题。页面文案可能是旧版/概括，不应据此把步骤分当第二主目标。

|---|---|---|---|
| 排名 | 成功率与步骤分综合 | **成功率优先；步骤分 tie-break；再并列看提交时间** | 只涨步骤分的优化降为近零价值 |

| 时间 | 180s | 不变 | 恢复/重试预算受总时长约束 |

## 2. 失败模型与主判断

### 2.1 30% 天花板的三种解释

| 解释 | 支持证据 | 反证/弱点 | 可操作性 |
|---|---|---|---|
| **模型容量/类别不足** | 30% 很低；VLA 在开放世界仍不成熟 | 4B/7B/14B、VLA/WAM 前三名打平；14B 不是第一 | 换更大模型，但边际收益可能很小 |
| **数据/覆盖不足** | 单一实验室（推断）；评测五轴；背景/干扰/未见/人未系统覆盖 | 数据量已有 33k/169h；位置轴有变化 | 补轴、增强、覆盖制图 |
| **接触/安全不足** | 最难任务集中在插入、拧盖、拉链、挂、取出；安全过滤真机有效 | 任务级噪声大；并非所有接触任务都难 | 接触感知安全层、终端伺服、恢复 |

本报告的判断：**容量不是当前最可操作的杠杆；覆盖和接触更可操作。** 这不是说模型不重要，而是说在 30% 附近，换模型的风险/成本高于加确定性安全层和补数据轴。CASF 和 SCA 都不改单一策略的权重（或只做轻量微调），因此风险可控。

### 2.2 统计证据

**标准误**：

\[
\mathrm{SE}(p)=\sqrt{\frac{p(1-p)}{n}}
\]

- 320 trials、p=0.25 → 2.42pp；p=0.30 → 2.56pp。取 **≈2.5pp**。
- 10 trials、p=0.25 → 13.7pp。逐任务排名不可靠。

**前三名**：29.7 / 28.5 / 27.9；差距 1.2 / 1.8 / 0.6pp，均小于 1 SE。**统计上打平**。这意味着“换第一名模型”不是一个可靠的 +1.8pp 策略；真实差异可能被噪声淹没。

**步骤分差**：设步骤分 \(s=\sum_i w_i p_i\)，成功率 \(p=\prod_i p_i\)。只要模型完成部分步骤，\(s>p\) 是正常的；差值是部分分结构的函数，且随整体能力同向变化。观测相关 0.87（模型级）/0.9999（任务级），说明它主要被整体能力解释。**不能从 +8.59pp 反推“失败在最后一步”**。要定位失败，必须看逐步日志/视频。

**任务路由**：原始 oracle 33.96%（+4.26pp），启发式收缩后 31.85%（+2.15pp）。每任务 10 trials 的最大值有向上偏差；单模型规则禁止混合；router 需要学的“谁更强”本身在噪声里。**不值得作为主轴。**

### 2.3 接触密集任务在底部过度代表

- 底部：Plug In Ethernet 17.7（插入）、Unlock 20.1（精密）、Organize Stationery 22.5（插入/整理）、Open Pill Bottle 22.7（拧盖）、Hang the Cup 23.0（挂）、Pick Out Battery 23.3（取出）、Zip Up 23.4（变形）。
- 顶部：Stack Cups 30.3、Conveyor Food Sorting 29.1、Place Photo Frames 28.0、Paper Cup Stacking 28.0。
- 反例：Spell robot 21.8 是放置；Stack Cups 是堆叠却相对容易。**任务类别不是决定性的**；10 trials/task 噪声也大。
- 稳妥结论：**接触密集任务是高杠杆的近失误来源**，CASF/SVL-2 应优先覆盖；不要声称“所有放置已解决”。

### 2.4 覆盖缺口

- 官方数据主要来自单一实验室（推断）；评测五轴是分布偏移。
- 位置轴：演示中目标位置有变化（随机摆放），覆盖相对好。
- 背景轴：演示的桌布/纹理单一；评测会换颜色/纹理。
- 干扰物轴：演示没有系统插入无关物体；评测会随机放杂物。
- 未见物品轴：演示是固定物体；评测会换同类不同外观。
- 人为干扰轴：官方备注给出逐任务剧本（平移/撤销），但演示中没有系统出现。
- **结论**：继续加同分布数据，不能补这四轴；SCA 的 3D 编辑 + 立体校验 + 动作重定向是对症的。

### 2.5 为什么不是更大模型/任务路由

- 4B WALL-OSS-0.5、7B MolmoAct2、14B DreamZero 前三名打平；规模/范式不是决定因素（在预览数据下）。
- 任务路由收缩后 +2.15pp，且违规；学习型 router 的复杂度/风险高于收益。
- 更大的模型会抬高推理延迟和部署成本，180s/远程 API 下不利于恢复/重试。
- 因此本轮把预算放在 **确定性安全层 + 数据轴**，而不是换模型。

## 3. CASF：接触感知的立体安全漏斗

### 3.1 几何与状态估计

**输入**：

- 左右高位 RGB：`cam_left_high` / `cam_right_high`（或数据集 `head_stereo_left/right`）。
- 本体：双臂关节、EE 位姿（base/torso）、夹爪、`lower_body`/`state_torso`。
- 任务：`observation.language`、SSG 当前步骤、任务规范（目标/容器/接触模式）。
- 标定：双目内参/外参、相机到头/躯干的变换、URDF、夹爪/附着物体几何。

**流程**：

1. **校正/匹配**：用离线标定的内参/外参校正；SGBM 或经典半全局匹配得到视差 \(d\)；深度 \(Z = f b / d\)。
2. **点云**：反投影到相机系，变换到 base 或桌面系；下采样到 1–2cm 体素。
3. **桌面平面**：RANSAC 拟合平面；用平面法向/高度建立桌面系，避免依赖 API 的 `state_d435`。
4. **物体聚类**：欧式聚类 + 颜色/几何先验；拟合椭球/胶囊/包围盒；容器用平面/开口模型。
5. **机器人几何**：URDF 正运动学；双臂、夹爪、**手里拿的物体**（附着几何）一起做碰撞检查。
6. **目标/障碍分解**：SSG + 任务规范 + 颜色/几何 + 可选注意力；跟踪用光流/点云运动。

**深度精度**：D435i 基线约 50mm，外部双目约 60mm（[S28][S29]）。1m 处、640px、0.5px 视差误差 → 约 1–2cm 深度误差。对 **碰撞避免** 足够；对 **毫米级插入** 不够。所以 CASF 负责安全，SVL-2/腕部视觉负责精插。

**标定策略**：

- 离线：用数据集的 `state_d435` + 双目图像 + 标定板/桌面平面，估计内参/外参。
- 在线：用桌面平面 + 机器人已知位姿做自标定；对 API 的缩放/压缩做一次分辨率/内参校验。
- 若 API 图像与数据集分辨率不同，重新估计焦距/主点，不要直接复用。

### 3.2 目标/障碍分解

| 任务族 | 目标 | 容器/接触对象 | 障碍 |
|---|---|---|---|
| 插入（T10/T26/T05） | 插头/网线 | 插排/网口 | 桌面、其他物体、人手 |
| 拧盖（T14） | 瓶盖 | 瓶身 | 桌面、其他物体 |
| 拉链（T18/T19/T23/T31） | 拉链头 | 布料/包 | 桌面、包体、其他物体 |
| 堆叠（T20/T25/T27） | 碗/杯 | 下层碗/杯 | 桌面、其他杯、人手 |
| 放置（T07/T08/T21 等） | 物体 | 架子/槽位 | 桌面、其他物体 |
| 取出（T11/T30） | 电池/钉子 | 盒子/板 | 周围积木、桌面 |

分解规则：

- SSG 的步骤文本给出目标（“grab the plug”“plug it into the power strip”）。
- 任务规范给出容器/槽位；颜色/几何先验给出候选。
- 目标在 **APPROACH** 阶段仍是障碍；进入 **ALIGN/INSERT/MANIPULATE** 才许可接触。
- 其他物体始终是障碍；人手/人臂是动态障碍，安全边距更大。
- 若目标定位不确定，回退到“全部障碍 + 保守接近”，宁可慢，不可撞。

### 3.3 接触模式与 CBF-QP

**状态**：\(x=(p_{ee}, R_{ee}, q)\)，\(p_{ee}\in\mathbb{R}^3\)，\(R_{ee}\in SO(3)\)，\(q\) 为关节。**控制**：EE 速度 \(u\in\mathbb{R}^6\) 或关节速度；策略输出先转成 EE 速度。

**障碍函数**：对每个障碍 \(i\)，用椭球/胶囊的 signed distance \(d_i(x)\)，定义

\[
h_i(x)=d_i(x)-r_{robot}-r_{obj}-m
\]

其中 \(m\) 是安全边距（静态 2cm，动态人手 5–8cm）。CBF 条件：

\[
\dot h_i(x,u)+\alpha h_i(x)\ge 0
\]

离散时间用：

\[
h_i(x_{t+1})\ge (1-\alpha\Delta t)h_i(x_t)
\]

**接触锥**：目标接触不是无限制的。设目标接触点 \(p_t\)、接近轴 \(n_t\)（从目标指向机器人），要求 EE 在轴周围的锥内：

\[
n_t^\top (p_{ee}-p_t)\ge \cos\theta_{max}\,\|p_{ee}-p_t\|
\]

\(\theta_{max}\) 按任务设定（插入 10–15°，堆叠 15–20°，放置 20–30°）。锥外仍然把目标当障碍。

**QP**：

\[
\min_{u}\ \|u-u_{nom}\|_2^2+\lambda\|u\|_2^2
\]

s.t.

\[
h_i(x_t)+\nabla h_i^\top u\,\Delta t\ge(1-\alpha\Delta t)h_i(x_t),\quad \forall i
\]

\[
\text{contact cone},\quad \text{joint limits},\quad \text{self-collision},\quad \|u\|_\infty\le u_{max}
\]

若 QP 不可行：降速、增大边距、回退到上一安全状态；连续不可行 → rollback。

**接触模式**：

| 模式 | 目标 | 其他物体 | 约束 |
|---|---|---|---|
| APPROACH | 障碍（5cm） | 障碍 | 标准 CBF；速度上限 |
| ALIGN | 允许进入锥 | 障碍 | 接触锥 + 侧向速度限制 |
| INSERT | 允许接触端口 | 障碍 | 轴向速度 + 力/深度监控 + 微摆动 |
| MANIPULATE | 允许持续接触 | 保护容器/桌面 | 支撑多边形 + 防倾倒 + 夹持力 |
| RETREAT | 重新变障碍 | 障碍 | 反向 CBF；沿来路撤退 |

**力/深度监控**：API 可能没有力传感器；用腕部视觉、EE 位姿变化、夹爪电流（若可读）做代理。插入卡住 → 微摆动/退回 2cm/重试；不要硬顶。

### 3.4 Rollback 与恢复

- 每 0.5s 保存最后安全 EE 位姿、关节、夹爪状态。
- CBF 不可行、接触丢失、谓词 1→0、或检测到人手进入安全区 → 撤退到安全位姿，重新观测，重新查询策略。
- 人类干扰：官方备注是 1-DOF 平移/撤销（[S34]）；检测目标运动 → 更新目标位姿；若步骤被撤销 → SSG 回退一步，复用 HSP/NRB 恢复动作。
- 预算：普通任务 ≤2 次重试；长程任务（T16/T17/T31）≤1 次；总时长守卫（Endurance Governor）兜底 180s。

### 3.5 伪代码

```python
class ContactAwareSafetyFunnel:
    def __init__(self, task_spec, calib, urdf):
        self.ssg = ScoreStepGraph(task_spec)
        self.stereo = StereoGeometry(calib)
        self.robot = WholeBodyModel(urdf, margin=0.02)
        self.target_prior = TargetPrior(task_spec)
        self.tracker = MotionTracker()
        self.cbf = CBFQP(self.robot)

    def filter(self, obs, action_chunk):
        step = self.ssg.current_step(obs)
        depth, cloud = self.stereo.reconstruct(obs.cam_left_high, obs.cam_right_high)
        table = fit_table_plane(cloud)
        objects = cluster_objects(cloud, table)
        target, obstacles = self.target_prior.decompose(step, objects, obs)
        obstacles = self.tracker.update(obstacles, obs)
        safe_chunk = []
        for action in action_chunk:
            mode = self.ssg.contact_mode(step)
            barriers = self.cbf.build_barriers(
                target, obstacles, mode, self.robot.fk(obs), table
            )
            safe = self.cbf.solve(action, barriers, mode)
            if safe is None:
                return self.rollback(obs, step)
            safe_chunk.append(safe)
        return safe_chunk

    def rollback(self, obs, step):
        pose = self.checkpoint.restore()
        self.ssg.rewind_if_needed(obs)
        return [pose]
```

### 3.6 延迟与单模型合规

- SGBM 480×640：约 10–20ms（CPU）；点云下采样 5ms；聚类/拟合 5–10ms；CBF-QP 1–2ms；总计 **<40ms**。策略推理 100–300ms，安全层可在 action chunk 之间异步运行。
- 若 chunk=8、30Hz（约 267ms），安全层有充足预算；必要时只对 chunk 的前几步做精确 CBF，后面用保守包络。
- **单模型合规**：CASF 是确定性包装层，不训练第二个策略；立体匹配、点云、RANSAC、CBF 都是几何/优化。若用 SAM2 做掩码，它是感知模块（Apache-2.0），需在模型卡披露；默认用颜色/几何/任务先验，避免争议。
- 每任务可配置接触模式/安全边距；这是代码配置，不是多模型。

### 3.7 预期效果、风险与消融

**预期**：

- 干扰物/人为干扰轴：碰撞率相对下降 30–60%；近失误转成功；轴内 +10–20pp。
- 整体：+1–3pp；干净场景不回归（回归 >2pp 则按任务关闭）。
- 步骤分：减少“撞倒后重来”的浪费，间接提升。

**风险**：

| 风险 | 影响 | 缓解 |
|---|---|---|
| 立体深度噪声/纹理缺失 | 碰撞检查误判 | 桌面平面先验、腕部相机、时间滤波、保守边距 |
| 透明/反光物体 | 深度缺失 | 用颜色/轮廓/任务先验；降低速度 |
| 标定误差 | 安全区偏移 | 在线自标定；每 episode 校验；失败回退 |
| 过度保守 | 接触任务失败 | 接触模式/锥角按任务调；干净场景 A/B；按任务开关 |
| 人手快速进入 | 碰撞 | 动态障碍 + 更大边距 + 立即减速/撤退 |
| 计算延迟 | 动作滞后 | 异步、chunk 前缀过滤、CPU 优化 |

**消融**：

1. 全障碍 CBF vs 接触许可 CBF。
2. 立体 vs 单目深度。
3. 静态障碍 vs 动态跟踪。
4. 有/无 rollback。
5. 有/无附着物体几何。
6. 不同安全边距/锥角。

## 4. SCA：立体一致的轴因子数据引擎

### 4.1 为什么 2D 增强不够

- 头部与腕部视角必须几何一致；2D 换背景/贴图会让两路视角对不上。
- 深度/遮挡关系被破坏；碰撞检查、抓取位姿、放置位姿都会错。
- 动作标签与场景不匹配；位置编辑后原动作可能抓空/放错。
- 评测是 3D 分布偏移（位置、背景、干扰物、未见物品、人），2D 增强只改纹理，不改 3D 结构。

### 4.2 3D 场景重建

对每条 episode：

1. 用校正双目 + SGBM/RAFT-Stereo 得到深度；反投影点云。
2. 用 `state_d435` 或桌面平面 + 机器人正运动学，把点云变换到桌面/base 系。
3. RANSAC 桌面平面；聚类物体；拟合 6D 位姿/包围盒/胶囊。
4. 用 SAM2（Apache-2.0）或颜色/几何分割得到物体掩码；跟踪得到时序位姿。
5. 用 EE 位姿/夹爪状态标注抓取/释放时刻；用 `score_steps` 对齐相位。
6. 存成场景图：桌面、物体（类别/位姿/尺寸/掩码）、相机、机器人、动作、语言。

**许可**：官方数据 Apache-2.0；SAM2 Apache-2.0；LeRobot Apache-2.0；Isaac Lab BSD-3。**FoundationPose 是非商用许可，不进推理/离线主路径**（[S35]）；6D 位姿用关键点 PnP/ICP/几何拟合替代。

### 4.3 五轴编辑配方

| 轴 | 编辑 | 动作标签 | 难度 | 备注 |
|---|---|---|---|---|
| 位置 | 目标/容器在桌面平移/旋转 | 桌面系刚体变换重定向接近/放置段 | 中 | 抓取段若物体已移动则需重抓/重生成 |
| 干扰物 | 插入官方场景物体（杯/工具/盒子） | CASF 生成避障；或重定向 | 中 | 不遮挡目标；不放在机器人本体上 |
| 背景 | 替换桌布/桌面纹理/背景 | 不变 | 低 | 用其他 episode 的纹理；保持阴影 |
| 未见物品 | 用相似 affordance 物体替换 | 抓取位姿迁移 + 轨迹调整 | 高 | 用官方其他任务的物体；先小规模 |
| 人为干扰 | 按 `human_1_note`/`human_4_note` 做 1-DOF 平移/撤销 | NRB 恢复动作 | 高 | 备注编号含义未核实；先做平移/撤销两类 |

**优先级**：先做背景（阶段 1）和位置（阶段 2），再做干扰物（阶段 3）；未见物品/人为干扰（阶段 4–5）视时间和资源。

### 4.4 动作重定向

- **背景**：动作不变；只需保证机器人/物体/阴影一致。
- **位置**：把目标/容器的 6D 位姿变化 \(T_{old}^{new}\) 应用到接近/放置段的 EE 位姿：
  \[
  T_{B}^{G,new}(t)=T_{B}^{R,new}\,(T_{B}^{R,old})^{-1}\,T_{B}^{G,old}(t)
  \]
  其中 \(R\) 是容器/桌面系。抓取段若物体在抓取前移动，原抓取动作无效；用策略重生成或抓取位姿迁移。
- **干扰物**：原动作可能碰撞；用 CASF 过滤生成避障动作，或在仿真中重规划。
- **未见物品**：用 affordance 关键点对齐抓取位姿；保持接近方向/夹持宽度；验证抓取稳定性。
- **人为干扰**：用 HSP 编译的扰动程序 + NRB 恢复动作；如果恢复动作不可得，用策略 rollback。

**验证**：仿真回放 + 人工抽检；检查动作是否到达目标、是否碰撞、夹爪是否闭合。动作标签有效率目标 >90%。

### 4.5 立体一致性校验

1. 用同一 3D 场景渲染左右目（或对 2D 编辑区域做双目 warping）。
2. 计算编辑区域的视差/深度；与原场景比较；极线误差/深度跳变超阈值 → 丢弃。
3. 检查遮挡顺序：前景物体不能穿到背景后面；阴影方向一致。
4. 训练一个 domain discriminator（真实 vs 增强）；AUC >0.8 说明太假，改进渲染/纹理。
5. 用真实 held-out 场景做小规模人评/策略回放。

### 4.6 覆盖制图（CCM）

- 对每个任务，从数据中提取目标/容器位姿、接近方向、背景嵌入、干扰物数量、物体外观嵌入。
- 在五轴上定义覆盖分数：位置用 k-center 覆盖/熵；背景用嵌入聚类；干扰物用数量/类型分布；未见物品用外观距离；人为干扰用剧本覆盖。
- 与评测五轴的目标分布比较，找出洞；优先补洞，而不是盲目加量。
- 输出：每任务×每轴的 coverage 热图；指导 SCA 采样和 L2L 采集（若允许）。

### 4.7 数据量与算力

- 官方 32k episodes；采样 20% = 6.4k；每条 5 种编辑 = 32k 增强样本。
- 若只做 8 个接触密集任务：8×1k×5 = 40k 编辑，但去重后约 8k–16k。
- 渲染/分割/重建：8×H100，2–3 周；存储约 5TB（视频+点云+掩码）。
- 训练：LoRA/action expert 微调，4B 模型 8×H100 约 3–5 天；7B 约 5–7 天。
- 资源有限：2×A100，先做背景+位置，8 个任务，LoRA。

### 4.8 预期效果、风险与消融

**预期**：

- 背景/位置/干扰物轴：+2–5pp；未见物品轴：+1–3pp；人为干扰轴：与 CASF/NRB 叠加。
- 整体：+1–3pp；比 2D 增强更保真。

**风险**：

| 风险 | 影响 | 缓解 |
|---|---|---|
| sim-to-real gap | 增强数据不迁移 | 用真实纹理/物体；discriminator；小规模真实 A/B |
| 外部数据政策 | 违规 | 默认只用官方数据/官方场景物体；外部资产先问官方 |
| 动作标签无效 | 学到错误动作 | 仿真回放/人工抽检；只对高置信样本训练 |
| 3D 重建误差 | 位姿/遮挡错 | 多视角校验；置信度过滤；腕部相机 |
| 计算/存储 | 成本高 | 分阶段；只做高 ROI 轴；8 任务优先 |

**消融**：

1. 无增强 vs 2D 增强 vs SCA。
2. 背景 only / 位置 only / 背景+位置 / 全五轴。
3. 有/无立体一致性校验。
4. 有/无动作重定向。
5. 真实 held-out 成功率 / 判别器 AUC / 动作有效率。

## 5. LCSA：多语言保险

### 5.1 风险

- 评测语言未写死；数据集是英文 5 复述；站点有中文描述；API 是单字符串。
- 非英语 VLA 掉点有文献证据（[S24]）；但 LangGap 提示语言可能被忽略（[S26]）。
- 头部模型的语言能力不同：Qwen 系可能中文更好；Molmo/Wan 系可能英文中心。不能假设。

### 5.2 语言审计（先做，便宜）

1. 32 任务 ×5 条英文复述 → 中文翻译（官方中文描述 + LLM 复述 + 人工校验）。
2. 选 8 个任务（4 接触密集 + 4 放置），每任务 5 次英文、5 次中文；共 80 trials。
3. 记录成功率、步骤分、失败模式；做人评/自动语言归因。
4. 判定：
   - 中文掉点 <5pp：跳过 LCSA。
   - 5–10pp：翻译增强（中文指令混入训练），不改结构。
   - >10pp：启用 LCSA。

### 5.3 LCSA 方法（条件启用）

- 只在对语言敏感的步骤（目标选择、空间关系、属性）做对齐；其他步骤用视觉/步骤上下文。
- 用多语言编码器（小型 mBERT/XLM-R 或模型自带 tokenizer）编码中文/英文指令；学习一个线性/低秩映射，使中文嵌入靠近英文嵌入（MPCA 风格）。
- 动作专家冻结；只训练对齐层（少量参数）。
- 训练数据：官方 5 英文复述 + 中文翻译 + 代码混合（中英夹杂）增强。
- 推理：按语言选择编码器；对齐层输出与原语言嵌入融合；不改变策略主干。

### 5.4 预期与 go/no-go

- 英文评测：0 增益；不要启用。
- 中文评测：+5–15pp（假设）。
- 风险：翻译伪影、语言标签噪声、额外延迟；用人工校验/小规模 A/B。
- **不把 LCSA 放进主路径**；它是保险，只有审计触发才做。

## 6. 系统集成：SAFE-PILOT

### 6.1 架构

```text
Offline
  官方 33k（LeRobot v3，四路相机，EE base/torso，5 复述）
    ├─ TLE：相位切分 + 谓词/接触标签 + 放置位姿库
    ├─ OPT：每任务容器系释放位姿统计 + 容差
    ├─ SCA：3D 重建 + 五轴编辑 + 立体校验 + 动作重定向
    ├─ CCM：五轴覆盖制图 + 补洞优先级
    ├─ HSP/NRB：官方 human 备注 → 扰动/恢复程序
    └─ LCSA（条件）：中文审计 + 对齐层

Online（单一 checkpoint + 确定性包装）
  observation.language
    → SSG-2：任务/步骤图；接触模式；谓词
  obs（4 RGB + proprio）
    → PGL：槽位→2D 锚点→6D 位姿（OPT 统计）
    → CASF：双目深度/点云/目标-障碍/接触锥/CBF-QP
    → GPR-VLA（WLA 底座 + LoRA/action expert）
    → SVL-2：伺服→缓放→settle→谓词→nudge/regrasp/retry
    → 执行；监控 → rollback / HSP 恢复
```

### 6.2 训练与推理

- **训练**：WLA-1.0-Base（Apache-2.0）+ LoRA/action expert；官方数据 + SCA 增强；HSP 恢复样本；可选 LCSA 对齐层。单 checkpoint。
- **推理**：单模型 + 确定性包装；CASF 在 action chunk 前过滤；SVL-2 在终端步闭环；SSG-2 管步骤/重试；180s 守卫。
- **延迟**：策略 100–300ms；CASF <40ms；SVL/rollback 只在终端/异常触发。目标 p99 <500ms/decision，满足 30Hz chunk。
- **失败处理**：谓词失败 → 重试；CBF 不可行 → rollback；超时 → 安全停止；语言不支持 → 回退英文/视觉。

### 6.3 单模型合规

- 一个策略 checkpoint；CASF/SSG/PGL/SVL 是确定性代码；SCA 是离线数据；LCSA 若启用是同一模型的小对齐层。
- 不做任务特定的多个 checkpoint；不做多模型路由；每任务配置是代码/参数，不是模型混合。
- 模型卡披露：安全层、立体标定、接触模式、语言支持、已知失败模式。

## 8. 实验矩阵

| 编号 | 问题 | 设置 | 指标 | Go/No-go |
|---|---|---|---|---|
| E0 | 双目标定/深度精度 | 数据集 + API 帧；桌面平面/标定板 | 重投影误差；1m 处深度误差 | <2cm 可用；否则只用近距/腕部 |
| E1 | CASF 离线回放 | 8 任务；合成干扰物/目标平移；名义动作 | 碰撞率；干预率；最小距离 | 碰撞相对 −30%；干净干预 <10% |
| E2 | CASF 延迟 | CPU；480×640 | p99 过滤时间 | <50ms |
| E3 | CASF 消融 | 全障碍 vs 接触许可；立体 vs 单目；静态 vs 动态；有无 rollback | 成功率/碰撞率 | 接触许可在接触任务 +10pp |
| E4 | SCA 真实感 | 判别器；立体一致性 | AUC；极线/视差误差 | AUC <0.8；一致性 >95% |
| E5 | SCA 动作有效性 | 仿真回放/人工抽检 | 有效动作比例 | >90% |
| E6 | SCA 真实增益 | 8 任务；背景/位置/干扰物 | 成功率 | 目标轴 +2pp |
| E7 | 调试槽 A/B | 4 接触 +4 放置；10 runs each | 成功率；步骤分；碰撞 | 总体 +3pp 或接触任务 +10pp |
| E8 | 全量计分跑 | 32×10；有/无 CASF+SCA | 总成功率；排名 | 相对基线 +2pp |
| E9 | 语言审计 | 8 任务×5 英/中 | 成功率差 | <5pp 跳过；>10pp LCSA |
| E10 | 逐步失败审计 | 调试槽视频/谓词 | 失败分类 | 找出 top-3 失败模式 |
| E11 | 标定鲁棒性 | 扰动外参/分辨率 | 成功率 | 掉点 <2pp |

**统计注意**：320 trials 的 SE≈2.5pp；80 trials 的 SE≈5pp。不要用 10–20 trials 的 A/B 宣称 +2pp。优先用 **碰撞率/干预率/逐步谓词** 这些更敏感的 proximal 指标做 go/no-go，再用调试槽/计分跑确认成功率。配对场景/任务可降方差；报告置信区间。

## 10. 风险、合规与开放问题

### 10.1 风险矩阵

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| 双目标定/深度不达精度 | 中 | 高 | 数据集离线标定；桌面平面；腕部相机；保守边距 |
| 安全层过度保守 | 中 | 高 | 接触模式/锥角按任务调；干净场景 A/B；按任务开关 |
| 透明/反光物体深度缺失 | 高 | 中 | 颜色/轮廓/任务先验；降速；腕部 |
| SCA sim-to-real gap | 中 | 高 | 真实纹理/物体；判别器；小规模真实 A/B |
| 动作标签无效 | 中 | 高 | 仿真回放/人工抽检；只训高置信 |
| 外部数据/资产许可 | 中 | 高 | 默认只用官方数据；外部资产先问官方 |
| 评测语言未知 | 高 | 中 | 语言审计；LCSA 条件启用 |
| 预览榜是占位 | 高 | 中 | 不据此下结论；真实榜单重跑 |
| 调试槽不足 | 中 | 高 | 离线回放 + 逐步审计；优先高价值任务 |
| 180s 超时 | 中 | 中 | Endurance Governor；重试上限；安全停止 |
| 单模型合规争议 | 低 | 高 | 确定性包装；模型卡披露；不混 checkpoint |

### 10.2 合规清单

- **单模型**：一个策略 checkpoint；CASF/SSG/PGL/SVL 是确定性代码；SCA 是离线数据；LCSA 若启用是同一模型的小对齐层；不做任务特定多 checkpoint/多模型路由。
- **数据**：官方数据 Apache-2.0（[S10]）；SCA 默认只用官方数据/官方场景物体；外部数据/资产先向官方确认；保留 NOTICE。
- **软件许可**：WLA-1.0-Base Apache-2.0（[S32]）；LeRobot Apache-2.0；SAM2 Apache-2.0；Isaac Lab BSD-3；**FoundationPose 非商用，避免**（[S35]）。
- **安全**：CASF 是确定性几何/优化，不训练第二策略；若用 SAM2，披露为感知模块。
- **模型卡**：安全层、标定、接触模式、语言支持、已知失败模式、训练数据/增强。
- **评测**：遵守 180s、单模型、远程 API、调试通道规则；不绕过评测。

### 10.3 开放问题

1. 真实榜单何时发布？预览数据是否由真实评测种子生成？
2. 评测指令语言是英文、中文，还是混合？是否会使用未见复述？
3. 外部数据/预训练权重是否允许？自采数据是否允许？
4. `cam_left_high`/`cam_right_high` 是否就是校正双目？基线/外参/分辨率/压缩是否与数据集一致？
5. 调试槽可用次数/成本/排期？
6. 人类备注的编号含义（轴/试次）？备注是否就是评测剧本？
7. 机器人台数/端口数？是否并行？
8. API 是否提供深度/IR/力/电流？若没有，CASF 的力监控只能用视觉/位姿代理。
9. 官方是否允许在推理侧加确定性安全层？模型卡披露是否足够？
10. 评测是否允许重置/重试？180s 内能否多次尝试？
