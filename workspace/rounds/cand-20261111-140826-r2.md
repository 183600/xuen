# 第 55 轮（承接第 54 轮 v31 GroundEdge-GenSim+++；灵感循环第 6 轮 / 本次会话第 2 轮；本轮灵感：「机器人」×「奖励设计」）

> 第 54 轮把技能从能力黑箱变为动作空间占用 `α_S`，并以 ACS/SCOM/CEC/AEC 建立动作-鲁棒性双证书。但存在一个被掩盖的缺口：**技能的行为由训练时的奖励函数塑造，动作兼容与鲁棒性谱只说明“能不能一起做”，没有说明“是否在追求同一目标”**。本轮借「机器人」与「奖励设计」视角，提出 **奖励剖面、势函数对齐、奖励黑客审计、主动偏好 elicitation**，把双证书扩展为动作-鲁棒性-奖励三证书。核心矛盾：H22：不同奖励训练出的技能在组合时发生目标干涉与奖励非平稳；H23：云端/仿真代理奖励与真实机器人任务奖励存在 gap，组合可能通过动作与鲁棒性检查，却在真实世界 reward-hack。

## 0. 直觉与动机

**灵感 1（机器人 → 技能不是函数，而是“被奖励塑造的行为”）**
直觉：对机器人而言，技能 `S` 是策略 `π_S` 在奖励 `r_S` 下优化的产物。动作剖面 `α_S` 只回答“能做什么”，鲁棒性谱 `ρ_S` 只回答“扰动下还能不能做”，二者都不回答“为何这样做”。因此需要 **奖励剖面 `β_S`**：把轨迹回报分解为安全、效率、能耗、舒适、可解释性等语义维度，使组合前可以追问：`S_i` 与 `S_j` 的偏好序是否一致？若不一致，动作层面的“兼容”只是假兼容。

**灵感 2（奖励设计 → 用势函数桥接把目标干涉变成可判定问题）**
直觉：Ng 等人的 potential-based reward shaping 告诉我们，`r' = r + γΦ(s') − Φ(s)` 不改变最优策略。若两个技能的奖励在动作交集上只差一个势函数差分（以及正比例尺度），则组合的最优策略与各自最优策略不冲突。这把“目标干涉”从模糊的经验判断，转化为 **势桥 `Φ_{ij}` 的存在性与残差大小** 的线性可行性问题。

**灵感 3（奖励设计 → 奖励黑客审计与反事实见证）**
直觉：机器人部署最怕代理奖励被利用——仿真里“看起来完成”、真实中“钻空子”。定义黑客间隙 `Hack = sup_π [J_proxy(π) − J_true(π)]`。动作剖面恰好给出红队可搜索的空间：在 `A_overlap` 上寻找“提升代理奖励、降低真实奖励”的策略见证。奖励证书必须附带 **反事实红队证据**，而不是只报一个代理回报数字。

**灵感 4（主动奖励 elicitation → 把人类偏好查询花在组合边界）**
直觉：真实奖励不可直接读取，但可以向人类做成对轨迹偏好查询。组合的歧义集中在技能切换边界 `ΔA` 与 `A_overlap`。主动 elicitation 应选择 **信息增益 × 决策影响** 最大的边界轨迹对，用最少查询把“接受/拒绝组合”的决策边界收缩到可置信区间内。

**灵感 5（三证书金字塔 → 动作·鲁棒性·奖励的统一）**
直觉：第 54 轮有双证书 `J=(ρ, A_cert, γ_ce, δ_a)`，本轮叠加奖励层 `ℛ`：`ℛ_0` 真实任务偏好，`ℛ_1` 技能奖励机，`ℛ_2` 组合势桥，`ℛ_3` 云边代理奖励。跨层传递证书需同时满足动作覆盖、鲁棒性下界、奖励对齐三项；任一项缺失即拒绝部署。这形成 **可解释的动作-鲁棒性-奖励三证书体系 `J3`**。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（技能奖励机与奖励剖面）**
技能 `S` 的奖励机 `RM_S = (Q_S, q_0, δ_S, r_S, AP, L)`：`Q_S` 为有限状态集，`δ_S: Q_S × A → Q_S` 为转移，`r_S: Q_S × A × Q_S → ℝ` 为伪奖励，`AP` 为命题集合，`L: Q_S → 2^{AP}` 为状态标签。技能奖励剖面 `β_S: 𝒯 → ℝ^m` 将轨迹分解为 m 个语义维度的回报向量；技能偏好序 `≽_S` 由权重 `w_S ∈ Δ^{m-1}` 标量化 `β_S(τ) = w_S^T β(τ)` 诱导。

**定义 122（奖励势桥与可对齐性）**
给定技能 `S_i,S_j` 与尺度 `c>0`，若存在势函数 `Φ: S → ℝ`，使动作交集 `A_overlap` 上几乎所有转移 `(s,a,s')` 满足
```
r_i(s,a,s') − c·r_j(s,a,s') = γΦ(s') − Φ(s)
```
则称二者 **奖励可对齐**，`Φ_{ij}` 为 **势桥**。其含义是：`r_i` 与 `c·r_j` 只差一个势函数差分，故 shaping 不改变二者共同的 `argmax`。令残差
```
ε_R(S_i,S_j) = min_{c>0, Φ∈ℱ} || r_i − c·r_j − (γΦ∘T − Φ) ||_{A_overlap,2}
```
定义奖励兼容性 `compat_R = exp(−ε_R / σ_R) ∈ (0,1]`。注意 `ℱ` 必须显式声明：若取 `Φ(s)=w^T φ(s)` 的线性基，则上式退化为最小二乘，残差可闭式计算。

**定义 123（奖励黑客间隙与奖励证书）**
设 `r_true` 为真实任务奖励（或人类偏好 oracle），`r_proxy` 为仿真/云端设计奖励。技能集 `Π_S` 上的黑客间隙
```
Hack(S, Π_S) = sup_{π∈Π_S} [ J_proxy(π) − J_true(π) ]
```
有限样本估计为 `Ĥack`，并记录见证集 `W = {(π_k, Δ_k)}`。奖励证书
```
R_cert = (r_proxy, r̂_true, Ĥack, ε_R, W, Elicit_trace)
```
若 `Ĥack + ε_R ≤ Θ_R` 且 `W = ∅`，则 `R_cert = 'safe'`。`W=∅` 只有在红队覆盖假设（A32）下才有意义，不能把“没找到”直接当作“不存在”。

**定义 124（主动偏好 elicitation）**
采用 Bradley–Terry 偏好模型 `P(τ_a ≻ τ_b | r) = σ(r(τ_a) − r(τ_b))`。查询空间 `Q = {(τ_a,τ_b) ⊂ 𝒯_{A_overlap}}`。查询选择
```
q* = argmax_{q∈Q} IG(q; r | D) · Impact(q)
```
其中 `IG` 为对后验 `p(r|D)` 的期望信息增益，`Impact(q)` 为组合接受/拒绝边界的 margin 敏感度。停止条件：后验熵 `H(r|D) ≤ ε_H` 或查询预算耗尽，输出后验均值 `r̂_true` 与置信区间。

**定义 125（奖励感知技能组合图与可行性）**
奖励感知组合图 `G_S^R = (V, E, W_R)`：边 `(i,j)` 除第 54 轮的 `compat(A) ≥ θ_a`、`c_trans ≤ τ_e`、`ρ_comp ≥ ρ_min` 外，还要求 `compat_R(S_i,S_j) ≥ θ_R`，并附带 `R_cert_{ij}`。奖励感知对齐成本
```
cost_align^R = w_a(1−compat) + w_ρ(1−ρ_comp) + w_R(1−compat_R) + w_h·max(0, Ĥack−Θ_R)
```
组合规划在 `G_S^R` 上寻找满足任务动作序列 `A_T` 且总成本最小的路径。

**定义 126（动作-鲁棒性-奖励三证书）**
```
J3 = (ρ, A_cert, R_cert, γ_ce, δ_a, δ_R, evidence)
```
其中 `δ_R = ||r̂_true − r_proxy||_{A_core}` 为奖励对齐误差上界。部署条件：
```
dom_J3(T)=in ∧ δ_a<Θ_a ∧ δ_R<Θ_R ∧ compat_R≥θ_R ∧ Ĥack≤Θ_R
```
跨轮迁移证书 JTC 扩展为 `J3TC`：目标域必须 **重新估计 r̂_true 与 Ĥack**，禁止直接继承源域奖励证书。

### IP-122 RPA（Reward Potential Alignment）

```python
def reward_potential_align(r_i, r_j, A_overlap, basis, gamma, sigma_R):
    # Φ(s) = w^T φ(s)，对每个尺度 c 解最小二乘
    best = None
    for c in grid(C_MIN, C_MAX):
        X, y = build_potential_system(r_i, r_j, A_overlap, basis, c, gamma)
        # 方程：γ w^T φ(s') − w^T φ(s) = r_i − c·r_j
        w, residual = lstsq(X, y)
        if best is None or residual < best.residual:
            best = (c, w, residual)
    eps_R = normalize(best.residual, A_overlap)        # 归一化到单位回报
    return Alignment(c=best.c, Phi=lambda s: basis(s) @ best.w,
                     eps_R=eps_R, compat_R=exp(-eps_R / sigma_R))
```

### IP-123 RHA（Reward Hacking Audit）

```python
def audit_reward_hacking(skill_seq, A_core, r_proxy, r_true, policy_space, budget):
    witnesses = []
    for pi in adversarial_search(policy_space, A_core, budget):   # ε-网 + 定向变异
        gap = expected_return(r_proxy, pi, A_core) - expected_return(r_true, pi, A_core)
        if gap > 0:
            witnesses.append((pi, gap))
    Hack_hat = max((g for _, g in witnesses), default=0.0)
    safe = (Hack_hat + eps_true <= Theta_R) and (len(witnesses) == 0)
    return Hack_hat, safe, witnesses
```

### IP-124 ARE（Active Reward Elicitation）

```python
def active_reward_elicitation(D, Q_pool, budget, eps_H):
    while posterior_entropy(D) > eps_H and budget > 0:
        q = max(Q_pool, key=lambda q: info_gain(q, D) * impact(q, D))
        label = human_oracle(q)                        # 返回 τ_a ≻ τ_b
        D = update_bradley_terry(D, q, label)
        budget -= 1
    return posterior_mean(D), credible_interval(D, alpha=0.05)
```

### IP-125 RACG（Reward-Aware Composition Graph）

```python
def build_reward_aware_graph(skills, theta_a, theta_R, tau_e, K):
    G = nx.DiGraph()
    for i, s1 in enumerate(skills):
        for j, s2 in enumerate(skills):
            if i == j: continue
            A_ov = intersection(s1.alpha, s2.alpha)
            if jaccard(s1.alpha, s2.alpha) < theta_a: continue
            if transition_cost(s1, s2) > tau_e:       continue
            ali = reward_potential_align(s1.r, s2.r, A_ov, BASIS, GAMMA, SIGMA_R)
            if ali.compat_R < theta_R:                continue
            hack, safe, W = audit_reward_hacking(
                (s1, s2), A_ov, s1.r_proxy, r_true, POLICY_SPACE, B_hack)
            if not safe:
                G.add_edge(i, j, blocked=True, reason='reward_hack', W=W)
                continue
            G.add_edge(i, j, compat=..., cost_align=cost_align_R(...),
                       rho_comp=compose_robustness(s1.rho, s2.rho, K),
                       Phi=ali.Phi, R_cert=RewardCert(ali, hack, W))
    return G
```

### IP-126 J3C（Joint Triple Certificate）

```python
def triple_certificate(skill_seq, gamma_ce, budgets):
    A_core = reduce(intersection, [s.alpha for s in skill_seq])
    delta_a = max_alignment_error(gamma_ce, A_core)
    rho = compose_robustness_chain([s.rho for s in skill_seq], K)
    ali = reward_potential_align_chain(skill_seq, A_core, BASIS, GAMMA)
    Hack_hat, safe, W = audit_reward_hacking(
        skill_seq, A_core, skill_seq[0].r_proxy, r_true, POLICY_SPACE, B_hack)
    if delta_a > Theta_a:
        return ('reject', 'action_mismatch', delta_a)
    if min(rho.values()) < rho_min:
        return ('reject', 'robustness_fail', rho)
    if ali.compat_R < theta_R or Hack_hat > Theta_R or not safe:
        return ('reject', 'reward_misaligned', ali, Hack_hat, W)
    A_cert = (A_core, buffer_zone(A_core, delta_a))
    R_cert = RewardCert(ali.compat_R, Hack_hat, eps_R=ali.eps_R, W=W,
                        trace=budgets.get('elicit_trace'))
    return ('ok', J3(rho, A_cert, R_cert, gamma_ce, delta_a, delta_R=ali.eps_R))
```

## 3. 玩具推导：为什么“动作兼容”不等于“目标一致”

设机器人有两个技能：`S_fast`（快速导航）奖励 `r_1 = −Δt`，`S_clean`（深度清洁）奖励 `r_2 = +Δcoverage`。在边走边清洁的动作交集 `A_overlap` 上，朴素组合 `r_1 + r_2` 的最优策略会偏向“快速低覆盖”或“慢速高覆盖”之一，取决于两奖励的量纲，而非任务真实偏好。若存在势桥 `Φ = −λ·dirt_remaining(s)`，则
```
r_1 + r_2 + γΦ(s') − Φ(s)
```
把“剩余脏污减少”显式计入转移，使组合的 argmax 与人类偏好序一致。反之，若线性基 `ℱ` 中不存在能解释该转移的 `Φ`，则残差 `ε_R` 大、`compat_R` 低，组合应在图搜索阶段被拒绝。这说明：**动作交集给出可行性候选，势桥残差才给出目标一致性判决**。

## 4. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| RMC | O(|traces|·|AP|·|Q|) | O(|Q|) | DFA 最小化、奖励可测 |
| RPA | O(|A_ov|·|ℱ|²) | O(|ℱ|) | 线性基完备、残差归一化 |
| RHA | O(B·|Π|·H) | O(|W|) | ε-网覆盖、真实奖励 held-out |
| ARE | O(B·|Q_pool|·H) | O(|D|) | 偏好模型校准、后验收缩 |
| RACG | O(|S|²·(|A|+|ℱ|²+B)) | O(|S|²+|E|) | 四重阈值 sound、成本单调 |
| J3C | O(|S|·|A|+|ℱ|²+B) | O(|A|+|W|) | 三证书预算闭合、见证可复现 |

**正确性定理（Reward-Aware Embodied Composition Soundness）**
承接第 54 轮 (A22)–(A28)；新增：
**(A29)** 每个 `RM_S` 有限且可测，`|r| ≤ R_max`；
**(A30)** 在 `A_core` 上 `r_true` 与 `r_proxy` 的差可被势桥加有界残差 `ε_R` 近似表示（近似 shaping 假设）；
**(A31)** elicitation 后验以概率 `1−δ_H` 落入 `ε_H` 球，且查询只落在 `A_overlap`；
**(A32)** 红队策略集是真实策略空间的 `ε_π`-网，且审计预算 `B_hack` 足够。
则组合部署成功概率
```
P_success ≥ 1 − Σ_d(1−ρ_min(d)) − β_E − P(δ_a>Θ_a)
              − P(compat_R<θ_R) − P(Hack>Θ_R) − ε_H − δ_H − ε_π
```
关键：**动作可行、鲁棒下界、奖励对齐三者同时成立才部署**；奖励证书不能从源域继承，必须在部署域重估。

## 6. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 奖励基函数 `ℱ` 过小导致假对齐 | 高 | 多基（线性/RBF/学习势）+ held-out 残差检验 + 拒绝低置信组合 |
| 红队未覆盖真实黑客策略 | 高 | ε-网 + 定向变异 + 随机化审计 + 外部 held-out 真实奖励 |
| 人类偏好噪声与疲劳 | 中 | Bradley–Terry 一致性检验 + 主动查询 + 高熵时弃权 |
| 奖励机状态爆炸 | 中 | 对称约简 + 分层奖励机 + 事件抽象 |
| 代理奖励随部署漂移 | 高 | 边端持续重估 `Hack` + 漂移阈值触发重审计 |

## 7. 本轮最大风险

**一句话**：势函数对齐与红队审计让“目标一致”变得可计算，但其 soundness **同时依赖奖励基 `ℱ` 的完备性、红队策略 ε-网对真实黑客策略的覆盖、以及人类偏好后验的可靠收缩**；一旦基过小把目标干涉误判为可对齐，或红队漏掉一个“动作安全、鲁棒达标、却优化错误目标”的策略，三证书就会给部署者虚假的安全感——故必须以 **多基残差检验 + 随机化红队 + 高熵弃权** 三重护栏，宁可拒绝组合，也绝不把代理奖励的对齐当作真实目标的一致。

# 第 55 轮产物 · 创新点清单 v32：GroundEdge-GenSim++++（RMC×RPA×RHA×ARE×RACG×J3C）

> 承接第 54 轮产物 v31（ACS×SCOM×CEC×AEC×JTC）。本轮引入「机器人」与「奖励设计」维度，在动作-鲁棒性双证书之上补齐“技能为何这样动”：
> - **RMC（Reward Machine Compiler）**：把技能训练奖励编译为有限奖励机与语义奖励剖面 `β_S`；
> - **RPA（Reward Potential Alignment）**：用势桥 `Φ_{ij}` 判定两技能奖励是否目标一致，输出 `compat_R`；
> - **RHA（Reward Hacking Audit）**：在动作交集上做反事实红队，估计 `Hack = J_proxy − J_true` 并记录见证；
> - **ARE（Active Reward Elicitation）**：在组合边界用信息增益 × 决策影响主动查询人类偏好；
> - **RACG（Reward-Aware Composition Graph）**：把动作、鲁棒性、奖励三阈值并入技能组合图；
> - **J3C（Joint Triple Certificate）**：动作-鲁棒性-奖励三证书 `J3`，升级跨轮迁移为 `J3TC`。
>
> IP 编号：IP-121~IP-126（共 6 个新增）。升级 IP-116/118/120：组合图与联合证书均增加奖励字段。

### IP-122 RPA

```python
def reward_potential_align(r_i, r_j, A_overlap, basis, gamma, sigma_R):
    # Φ(s)=w^T φ(s)；对每个尺度 c 解线性最小二乘
    best = None
    for c in grid(C_MIN, C_MAX):
        X, y = build_potential_system(r_i, r_j, A_overlap, basis, c, gamma)
        # 约束方程：γ w^T φ(s') − w^T φ(s) = r_i − c·r_j
        w, residual = lstsq(X, y)
        if best is None or residual < best.residual:
            best = (c, w, residual)
    eps_R = normalize(best.residual, A_overlap)
    return Alignment(c=best.c, Phi=lambda s: basis(s) @ best.w,
                     eps_R=eps_R, compat_R=exp(-eps_R / sigma_R))
```

### IP-123 RHA

```python
def audit_reward_hacking(skill_seq, A_core, r_proxy, r_true, policy_space, budget):
    witnesses = []
    for pi in adversarial_search(policy_space, A_core, budget):   # ε-网 + 定向变异
        gap = expected_return(r_proxy, pi, A_core) - expected_return(r_true, pi, A_core)
        if gap > 0:
            witnesses.append((pi, gap))
    Hack_hat = max((g for _, g in witnesses), default=0.0)
    safe = (Hack_hat + eps_true <= Theta_R) and (len(witnesses) == 0)
    return Hack_hat, safe, witnesses
```

### IP-124 ARE

```python
def active_reward_elicitation(D, Q_pool, budget, eps_H):
    while posterior_entropy(D) > eps_H and budget > 0:
        q = max(Q_pool, key=lambda q: info_gain(q, D) * impact(q, D))
        label = human_oracle(q)                      # τ_a ≻ τ_b
        D = update_bradley_terry(D, q, label)
        budget -= 1
    return posterior_mean(D), credible_interval(D, alpha=0.05)
```

### IP-125 RACG

```python
def build_reward_aware_graph(skills, theta_a, theta_R, tau_e, K):
    G = nx.DiGraph()
    for i, s1 in enumerate(skills):
        for j, s2 in enumerate(skills):
            if i == j: continue
            A_ov = intersection(s1.alpha, s2.alpha)
            if jaccard(s1.alpha, s2.alpha) < theta_a: continue
            if transition_cost(s1, s2) > tau_e:       continue
            ali = reward_potential_align(s1.r, s2.r, A_ov, BASIS, GAMMA, SIGMA_R)
            if ali.compat_R < theta_R:                continue
            hack, safe, W = audit_reward_hacking(
                (s1, s2), A_ov, s1.r_proxy, r_true, POLICY_SPACE, B_hack)
            if not safe:
                G.add_edge(i, j, blocked=True, reason='reward_hack', W=W)
                continue
            G.add_edge(i, j, compat=..., cost_align=cost_align_R(...),
                       rho_comp=compose_robustness(s1.rho, s2.rho, K),
                       Phi=ali.Phi, R_cert=RewardCert(ali, hack, W))
    return G
```

### IP-126 J3C

```python
def triple_certificate(skill_seq, gamma_ce, budgets):
    A_core = reduce(intersection, [s.alpha for s in skill_seq])
    delta_a = max_alignment_error(gamma_ce, A_core)
    rho = compose_robustness_chain([s.rho for s in skill_seq], K)
    ali = reward_potential_align_chain(skill_seq, A_core, BASIS, GAMMA)
    Hack_hat, safe, W = audit_reward_hacking(
        skill_seq, A_core, skill_seq[0].r_proxy, r_true, POLICY_SPACE, B_hack)
    if delta_a > Theta_a:
        return ('reject', 'action_mismatch', delta_a)
    if min(rho.values()) < rho_min:
        return ('reject', 'robustness_fail', rho)
    if ali.compat_R < theta_R or Hack_hat > Theta_R or not safe:
        return ('reject', 'reward_misaligned', ali, Hack_hat, W)
    A_cert = (A_core, buffer_zone(A_core, delta_a))
    R_cert = RewardCert(ali.compat_R, Hack_hat, eps_R=ali.eps_R, W=W,
                        trace=budgets.get('elicit_trace'))
    return ('ok', J3(rho, A_cert, R_cert, gamma_ce, delta_a, delta_R=ali.eps_R))
```

### IP-120+ J3TC（跨轮迁移）

```python
def triple_transfer_certify(J3_source, L_target, phi, budgets):
    # 关键变化：奖励证书不得继承，必须在目标域重估 r_true 与 Hack
    r_true_t = estimate_true_reward(L_target, phi, budgets['elicit'])
    hack_t, safe_t, W_t = audit_reward_hacking(
        phi.skill_seq, phi.A_core, J3_source.R_cert.r_proxy,
        r_true_t, L_target.policy_space, budgets['hack'])
    if not safe_t or hack_t > Theta_R:
        return ('reject', 'target_reward_hack', hack_t, W_t)
    ali_t = reward_potential_align_chain(phi.skill_seq, phi.A_core, BASIS, GAMMA)
    delta_rho = coupling_drift(J3_source.rho, L_target, phi)
    delta_a = alignment_drift(J3_source.gamma_ce, phi)
    if sum(delta_rho.values()) > budgets['rho'] or delta_a > budgets['a']:
        return ('reject', 'budget_exceeded', delta_rho, delta_a)
    return ('ok', J3TC(J3_source, L_target, phi, ali_t, hack_t, W_t, delta_rho, delta_a))
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| RMC | O(|traces|·|AP|·|Q|) | O(|Q|) | DFA 最小化、奖励可测 |
| RPA | O(|A_ov|·|ℱ|²) | O(|ℱ|) | 线性基完备、残差归一化 |
| RHA | O(B·|Π|·H) | O(|W|) | ε-网覆盖、真实奖励 held-out |
| ARE | O(B·|Q_pool|·H) | O(|D|) | 偏好模型校准、后验收缩 |
| RACG | O(|S|²·(|A|+|ℱ|²+B)) | O(|S|²+|E|) | 四重阈值 sound、成本单调 |
| J3C | O(|S|·|A|+|ℱ|²+B) | O(|A|+|W|) | 三证书预算闭合、见证可复现 |

**正确性定理（Reward-Aware Embodied Composition Soundness）**
承接第 54 轮 (A22)–(A28)；新增 **(A29)** 奖励机有限且可测、`|r|≤R_max`；**(A30)** `r_true` 与 `r_proxy` 之差在 `A_core` 上可被势桥加有界残差 `ε_R` 近似；**(A31)** elicitation 后验以概率 `1−δ_H` 落入 `ε_H` 球；**(A32)** 红队策略集为真实策略空间的 `ε_π`-网且预算充足。则
```
P_success ≥ 1 − Σ_d(1−ρ_min(d)) − β_E − P(δ_a>Θ_a)
              − P(compat_R<θ_R) − P(Hack>Θ_R) − ε_H − δ_H − ε_π
```
三项判据缺一不可：**动作可执行、鲁棒性达标、奖励目标对齐**。奖励证书是域相关的，不能在迁移时继承。

## 5. 本轮最大风险

**一句话**：势函数对齐与红队审计让“目标一致”变得可计算，但其 soundness **同时依赖奖励基 `ℱ` 的完备性、红队策略 ε-网对真实黑客策略的覆盖、以及人类偏好后验的可靠收缩**；一旦基过小把目标干涉误判为可对齐，或红队漏掉一个“动作安全、鲁棒达标、却优化错误目标”的策略，三证书就会给部署者虚假的安全感——故必须以 **多基残差检验 + 随机化红队 + 高熵弃权** 三重护栏，宁可拒绝组合，也绝不把代理奖励的对齐当作真实目标的一致。
