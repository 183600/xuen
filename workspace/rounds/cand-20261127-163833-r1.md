### 第 1 轮灵感驱动研究记录

**灵感词**：预测性维护、上下文理解

**直觉与动机**：

当前 CADVS/KEMPC 体系的证书几乎都是「瞬时证书」——它们回答的是「此刻这一步是否安全」。但真实世界的失效大多是慢变量累积的结果：关节轴承磨损、电池内阻上升、减速器间隙增大、IMU 零偏漂移、标定参数老化。瞬时证书无法表达一个关键命题：「现在安全，但按当前工况再运行 20 分钟，就会越过安全边界」。预测性维护（PdM）提供的正是这个慢时间尺度：用退化状态与剩余寿命（RUL）把「未来失效概率」变成控制层可消费的证书。

但 PdM 单独使用会犯一个根本性错误——**退化归因混淆**。同一段振动频谱升高、同一路电流纹波变大、同一处温升，既可能是「重载爬坡」造成的可逆负载，也可能是「轴承早期故障」造成的不可逆退化。没有上下文，RUL 模型会把工况载荷误记为故障进展，或把早期故障误记为正常负载。上下文理解（Context Understanding）因此不是可选的感知增强，而是 PdM 的**可辨识性条件**：它提供条件变量 c，把观测分解为「工况诱导的可逆分量」与「故障诱导的不可逆分量」。

反过来也成立：上下文理解若没有慢时间尺度，会把渐变的地形/负载/任务漂移误判为瞬时上下文切换，导致 KC 规则频繁抖动。因此二者是互补的：**上下文为退化去混杂，退化为上下文提供时间先验**。

**关键洞见**：不要把它理解成「在 CADVS 上再加一个 RUL 预测器和一个场景分类器」。真正的研究对象是**证书语义的升级**：从「此刻是否安全」升级为「在当前上下文下，未来 H 步内以 1−ε 概率安全」。这要求快慢双环：快环（证书/控制，毫秒级）继续使用瞬时证书；慢环（上下文/退化，秒到小时级）持续签发**前瞻性证书**，并用一致性监控把慢环的不确定性注入快环的降额与回退。预测性维护由此从「运维告警」变成「控制约束」，上下文理解由此从「感知标签」变成「证书有效性的条件变量」。

**严谨定义（增量）**：

1. **上下文与上下文证书**：上下文 c_t ∈ C（地形、负载、步态相位、任务阶段、人机模式、环境光照/摩擦等）。上下文后验 p_t(c) = P(c_t = c | o_{1:t}) 由贝叶斯滤波给出。定义上下文证书
   CC = (c*, p*, H*, t, Δt_val, calib)，
   其中 c* = argmax_c p_t(c)，p* = max_c p_t(c)，H* = −Σ_c p_t(c) log p_t(c) 为后验熵，calib 为校准检验结果。CC 有效当且仅当 H* ≤ H_max、p* ≥ p_min、calib 通过且未过期。

2. **退化状态与预后证书**：对每个关键部件 j，退化状态 z_t^{(j)} ∈ ℝ^{d_j} 服从上下文条件随机微分方程
   dz = μ(z, c, u) dt + Σ(z, c) dW，
   健康指数 h^{(j)} = 1 − z^{(j)} / z_fail^{(j)}，剩余寿命 τ^{(j)} = inf{s ≥ 0 : z_{t+s}^{(j)} ≥ z_fail^{(j)}}。定义预后证书
   PDC = (h, F_τ, t_upd, Δt_val, conf, ood)，
   其中 F_τ 为 RUL 的预测分布（至少给出 q10/q50/q90 与完整 CDF），conf 为预测后验校验（PIT/CRPS）结果，ood 为分布外标志。PDC 有效当且仅当未过期、后验校验通过且 ood = false；ood = true 时只能以「保守上界」形式使用。

3. **上下文条件 KC**：规则 i 的激活谓词由 φ_i(x, c) ≥ θ_i(c) 给出，权重为 λ_i(c)。上下文只允许两种改变：**增加约束**（激活更多规则）或**受保护地删除约束**（去激活）。去激活必须附带冗余证书 R_i(c)：证明在上下文 c 下，被删规则在剩余约束的可达集上恒不活跃，或由其他规则蕴含。记该保护谓词为 G_i(c)。没有 G_i(c) 的去激活一律禁止。

4. **机会约束**：给定规划时域 H 与风险预算 ε，
   P(τ ≤ H | z_t, c_t) ≤ ε。
   PMA-MPC 在满足该机会约束的前提下最小化
   J = 跟踪代价 + λ_deg · E[Δz_{t:t+H}] + λ_maint · 维护紧迫度惩罚 + λ_u · ‖u‖²，
   其中 λ_deg 惩罚会加速退化的控制动作（如高频抖动、过大电流、过大接触力）。

5. **执行集目标**：Exec_PCM ⊆ Exec_CADVS ⊆ Exec_v29。即上下文/预后只能收紧或经证明等价地替换约束，不能凭空放宽 v29 的证书约束。

**形式化目标（增量）**：

1. 定义 CC、PDC 及其有效性条件，给出「过期/失准/分布外」三种降级语义。
2. 定义上下文条件 KC 的受保护激活/去激活规则 G_i(c)，并证明 Exec_PCM ⊆ Exec_CADVS。
3. 定义上下文条件退化模型 μ(z,c,u) 与机会约束 MPC，证明在校准上下文与保守退化模型下，非计划失效概率 ≤ ε + δ_c + δ_prog。
4. 定义双时间尺度有效性界：若退化轨迹关于时间 L-Lipschitz，则慢环更新间隔 Δt_prog ≤ δ_h / L 时，快环使用陈旧 PDC 造成的健康指数误差不超过 δ_h。
5. 定义上下文—退化可辨识性条件：至少需要观察到两次有效上下文切换且设计矩阵非奇异，否则「负载诱导」与「故障诱导」不可区分；CPCM 必须显式报告这一不可辨识性，而非给出虚假的高置信 RUL。
6. 实验验证：相对 CADVS v29，非计划失效下降 ≥ 45%，不必要维护下降 ≥ 25%，RUL 90% 区间覆盖率落在 [88%, 93%]，快环额外开销 < 0.3 ms，慢环 1 Hz 下单次 < 5 ms。

**本轮最大风险**：**上下文—预后共享不可观测混杂因子**——当机器人长期处于单一工况（上下文缺乏激励）时，负载诱导的可逆退化与故障诱导的不可逆退化在统计上不可辨识；系统可能以高置信度把「重载磨损」误判为「健康」或把「早期故障」误判为「工况负载」，从而在最需要维护时签发「未来 H 步安全」的证书。这是一种跨时间尺度的**虚假安全**，比瞬时证书失效更隐蔽，因为它不会立刻触发违规，却会系统性地推迟正确维护。

## 2. 关键算法骨架

### IP-478 Context-Aware Knowledge Router (CAKR)

```python
@dataclass
class ContextAwareKnowledgeRouter:
    """CAKR：贝叶斯上下文滤波 + 校准检验 + 受保护 KC 路由"""
    contexts: list[str] = field(default_factory=lambda: [
        'flat', 'slope_up', 'slope_down', 'rough', 'stairs',
        'loaded', 'unloaded', 'human_near', 'low_light'
    ])
    H_max: float = 0.35          # 后验熵上界（nats）
    p_min: float = 0.60          # 众数概率下界
    kappa_calib_max: float = 0.20
    guard_margin: float = 0.10   # 预后紧迫度超过此值则禁止去激活
    theta_base: dict[str, float] = field(default_factory=dict)
    delta_theta: dict[tuple[str, str], float] = field(default_factory=dict)

    def update(self, obs: ContextObservation, dt: float) -> ContextCertificate:
        # 1) 预测：p^-(c) = Σ_{c'} T_{c'c} p(c')
        prior = self.transition @ self.posterior
        # 2) 观测更新：p(c|o) ∝ L(o|c) p^-(c)
        lik = self.likelihood(obs)
        post = prior * lik
        post = post / max(float(post.sum()), 1e-12)
        self.posterior = post
        c_star = self.contexts[int(np.argmax(post))]
        p_star = float(np.max(post))
        H = float(-(post * np.log(post + 1e-12)).sum())
        # 3) 校准：温度缩放 + 可靠性图斜率检验
        calib_ok = self._calibration_check(post, obs)
        valid = (H <= self.H_max and p_star >= self.p_min and calib_ok)
        return ContextCertificate(
            c_star=c_star, p_star=p_star, entropy=H,
            t=obs.t, validity_window=2.0 * dt, valid=valid,
            calibration_ok=calib_ok
        )

    def route(self, x: np.ndarray, cc: ContextCertificate,
              pdc: PrognosticCertificate) -> dict[str, bool]:
        """只允许两种改变：增加约束，或带冗余证书的去激活。"""
        active: dict[str, bool] = {}
        for kc in self.kcs:
            phi = kc.evaluate(x, cc.c_star)
            theta = self.theta_base[kc.name] + \
                    self.delta_theta.get((kc.name, cc.c_star), 0.0)
            want = phi >= theta
            # 去激活是危险方向：无保护则保守保留
            if not want and not self._guarded_deactivation(kc, cc, pdc):
                want = True
            active[kc.name] = want
        return active

    def _guarded_deactivation(self, kc, cc, pdc) -> bool:
        # 三条件同时满足才允许去激活
        if not cc.valid or not pdc.valid:
            return False
        if pdc.urgency > self.guard_margin:
            return False
        # 冗余证书：证明被删规则在剩余约束的可达集上恒不活跃
        return kc.redundancy_certificate(cc.c_star)
```

**设计要点**：上下文可以「多激活」规则（更保守），但「少激活」必须给出冗余证明。这条不对称规则是执行集包含性 `Exec_PCM ⊆ Exec_CADVS` 的算法根基。

### IP-479 Prognostic Degradation Certificate (PDC)

```python
@dataclass
class PrognosticDegradationCertificate:
    """PDC：上下文条件退化模型 + 粒子滤波 RUL + 后验校验 + OOD 保守上界"""
    components: list[str] = field(default_factory=lambda: [
        'joint_bearing', 'battery', 'imu', 'actuator'
    ])
    z_fail: dict[str, float] = field(default_factory=lambda: {
        'joint_bearing': 1.0, 'battery': 1.0, 'imu': 1.0, 'actuator': 1.0
    })
    n_particles: int = 2000
    dt_prog: float = 1.0
    eps: float = 1e-3
    ood_max: float = 0.30
    alpha_c: dict[tuple[str, str], float] = field(default_factory=dict)
    beta_wear: dict[str, float] = field(default_factory=dict)

    def predict(self, z: dict[str, np.ndarray], u: np.ndarray,
                cc: ContextCertificate, horizon: float) -> dict[str, PDC]:
        certs = {}
        for comp in self.components:
            # 1) 上下文条件漂移：μ = μ0(z) + α_{c,comp} + β·‖u‖²
            mu = self._drift(z[comp], cc.c_star, u, comp)
            # 2) 粒子传播：z_{t+Δ} = z_t + μΔ + Σ√Δ·ξ
            particles = self._propagate(z[comp], mu, horizon)
            # 3) 首次穿越时间分布
            F_tau = self._first_passage(particles, self.z_fail[comp])
            h = 1.0 - float(np.mean(particles[:, -1])) / self.z_fail[comp]
            # 4) 预测后验校验：PIT 均匀性 + CRPS
            conf = self._posterior_check(F_tau)
            ood = self._ood_score(cc, z[comp]) > self.ood_max
            certs[comp] = PDC(
                h=h, F_tau=F_tau, t_upd=time.time(),
                validity_window=self.dt_prog * 3,
                conf=conf, ood=ood,
                # OOD 时只允许保守上界，禁止使用点预测
                upper_envelope=F_tau.upper_bound() if ood else None
            )
        return certs

    def _drift(self, z, c, u, comp):
        return (self.mu0(z, comp)
                + self.alpha_c.get((c, comp), 0.0)
                + self.beta_wear.get(comp, 0.0) * float(np.sum(u ** 2)))

    def conservative_fail_prob(self, pdc: PDC, H: float) -> float:
        if pdc.ood:
            return float(pdc.upper_envelope(H))
        return float(pdc.F_tau(H))
```

**关键语义**：`ood=True` 不是「删除证书」，而是「把点预测替换为保守上界」。这保证分布外时仍然可以安全降额，而不是直接失去维护能力。

### IP-480 Prognostic-Maintenance-Aware MPC (PMA-MPC)

```python
def pma_mpc_step(x: np.ndarray, cc: ContextCertificate,
                 pdc: dict[str, PDC], model, cfg) -> np.ndarray:
    # 0) 证书无效 → 回退 CADVS v29，不在坏证书上做预测控制
    if not cc.valid or any(not p.valid for p in pdc.values()):
        return cadvs_step(x, model.sensor, reason='cc_or_pdc_invalid')

    # 1) RUL 自适应降额：健康越差，控制包络越紧
    h_min = min(p.h for p in pdc.values())
    derate = float(np.clip((h_min - cfg.h_min) /
                           (cfg.h_safe - cfg.h_min), 0.0, 1.0))
    u_max_eff = cfg.u_max * derate

    # 2) 机会约束：对上下文可信集取最坏情形
    def chance_ok(u_seq):
        for c in cc.credible_set(delta=cfg.delta_c):
            for _ in range(cfg.n_scenarios):
                z_s = sample_degradation(pdc, c, u_seq)
                for comp in pdc:
                    if pdc[comp].conservative_fail_prob(z_s, cfg.H) > cfg.eps:
                        return False
        return True

    # 3) 场景 MPC：跟踪 + 退化率惩罚 + 维护紧迫度 + 控制能量
    def objective(u_seq):
        return (tracking_cost(x, u_seq)
                + cfg.lambda_deg * expected_degradation_increment(u_seq)
                + cfg.lambda_maint * max(p.urgency for p in pdc.values())
                + cfg.lambda_u * float(np.sum(u_seq ** 2)))

    u_seq = solve_mpc(
        objective=objective,
        constraints=[model.dynamics, model.safety,
                     chance_ok, ('u_max', u_max_eff)],
        horizon=cfg.N
    )
    return u_seq[0]
```

**与 v29 的接口**：PMA-MPC 不替代 KT-MPC，而是在其外层增加 `derate` 与 `chance_ok` 两个约束。跟踪代价、十二证聚合、教师/学生切换逻辑原样复用。

### IP-481 Context-Prognosis Consistency Monitor (CPCM)

```python
@dataclass
class ContextPrognosisConsistencyMonitor:
    """CPCM：上下文—退化互证 + 模型漂移 CUSUM + 可辨识性报告"""
    window: int = 600
    cusum_k: float = 0.5
    cusum_h: float = 5.0
    kappa_max: float = 30.0

    def update(self, z_obs: np.ndarray, c_obs: str,
               pdc: PDC, t: float) -> ConsistencyReport:
        self.buffer.append((t, z_obs, c_obs))
        if len(self.buffer) > self.window:
            self.buffer.pop(0)

        # 1) 线性归因模型：z_t = z0 + β t + Σ_c α_c · t·1[c_t=c] + ε
        X, y = self._design_matrix(self.buffer)
        kappa = float(np.linalg.cond(X)) if X.size else float('inf')
        identifiable = kappa < self.kappa_max

        # 2) 残差 CUSUM：检测未建模故障或模型老化
        residual = float(z_obs - pdc.predict_mean(t))
        self.cusum = max(0.0, self.cusum + residual - self.cusum_k)
        if self.cusum > self.cusum_h:
            return ConsistencyReport(
                violation=True, reason='degradation_model_drift',
                identifiable=identifiable, kappa=kappa,
                attribution=None
            )

        # 3) 上下文激励不足：不伪造归因，显式报告不可辨识
        if not identifiable:
            return ConsistencyReport(
                violation=False, reason='context_not_excited',
                identifiable=False, kappa=kappa, attribution=None
            )

        # 4) 归因：β 显著且 α 不显著 → 故障；α 显著且 β 不显著 → 负载
        beta_hat, alpha_hat = self._ols(X, y)
        attribution = self._attribute(beta_hat, alpha_hat)
        return ConsistencyReport(
            violation=False, reason='consistent',
            identifiable=True, kappa=kappa, attribution=attribution
        )
```

**归因逻辑的严谨性**：只有当设计矩阵非奇异时，`β`（故障趋势）与 `α_c`（上下文载荷）才可分离。若机器人长期只在平地上运行，`t` 与 `t·1[c=flat]` 共线，任何算法都无法仅凭数据区分「负载磨损」与「故障进展」。CPCM 必须把这一点报告为 `context_not_excited`，并让下游退化为保守维护策略。

### IP-482 Maintenance Action Certificate Scheduler (MACS)

```python
@dataclass
class MaintenanceActionCertificateScheduler:
    """MACS：把 RUL 证书转成可执行的维护请求 + 安全运行包络"""
    tau_maint: float = 30 * 60.0      # 维护提前量（秒）
    eps_maint: float = 1e-2
    hysteresis: float = 0.10

    def evaluate(self, pdc: dict[str, PDC], cc: ContextCertificate,
                 t: float) -> MaintenanceAction:
        urgent = any(
            p.q10_tau < self.tau_maint or
            p.fail_prob(self.tau_maint) > self.eps_maint
            for p in pdc.values()
        )
        if not urgent:
            return MaintenanceAction.NONE

        envelope = self._safe_operating_envelope(pdc, cc)
        return MaintenanceActionCertificate(
            request='schedule_maintenance',
            deadline=t + min(p.q10_tau for p in pdc.values()),
            envelope=envelope,
            derate_until_service=envelope.derate,
            audit={
                'pdc': {k: v.summary() for k, v in pdc.items()},
                'cc': cc.summary(),
                'identifiable': cc.identifiable
            }
        )

    def _safe_operating_envelope(self, pdc, cc):
        # 在最坏上下文与最坏部件上求可行控制包络
        h_worst = min(p.h for p in pdc.values())
        return SafeEnvelope(
            derate=float(np.clip(h_worst, 0.2, 1.0)),
            max_speed=...,
            max_payload=...,
            forbidden_contexts=self._high_stress_contexts(cc)
        )
```

### 快慢双环统一执行流

```python
def pcm_step(x: np.ndarray, obs: ContextObservation, t: float) -> ControlOutput:
    """快环每步执行；慢环按 Δt_prog 更新上下文与预后证书。"""
    # ---------- 慢环（1 Hz） ----------
    if t - state.last_slow >= cfg.dt_prog:
        cc = cakr.update(obs, cfg.dt_prog)
        pdc = pdc_estimator.predict(state.z, state.u_prev, cc, cfg.H)
        report = cpcm.update(state.z_obs, cc.c_star, pdc, t)
        if report.violation:
            # 模型漂移：加宽 RUL 上界 + 禁止上下文去激活
            pdc = inflate_conservative(pdc)
            cc = cc.degrade_for_deactivation()
        state.last_slow = t

    # ---------- 快环（每步） ----------
    if not cc.valid or any(not p.valid for p in pdc.values()):
        return cadvs_step(x, obs, reason='slow_loop_cert_invalid')

    active = cakr.route(x, cc, pdc)
    u = pma_mpc_step(x, cc, pdc, model, cfg)

    cert = aggregate_certs(active, cc, pdc)
    if not cert.all_passed:
        return cadvs_step(x, obs, reason='pcm_cert_aggregate_fail')

    # 维护请求作为旁路证书，不阻塞控制，但强制降额
    maint = macs.evaluate(pdc, cc, t)
    if maint is not MaintenanceAction.NONE:
        u = apply_envelope(u, maint.envelope)
        cert = cert.with_maintenance(maint)

    return ControlOutput(u, path='pcm', certs=cert)
```

## 4. 正确性论证（增量）

### 定义 1（受保护去激活）

对 KC 规则 i 与上下文 c，去激活谓词 `G_i(c)` 为真当且仅当：

1. CC 有效（`H* ≤ H_max`、`p* ≥ p_min`、校准通过、未过期）；
2. PDC 有效且维护紧迫度 `urgency ≤ guard_margin`；
3. 存在冗余证书 `R_i(c)`，证明在剩余激活规则与物理约束共同定义的可达集 `Reach(c)` 上，规则 i 的约束恒不活跃（或被其他规则蕴含）。

### 引理 32（执行集包含性）

**陈述**：若每一次上下文引起的规则变化要么是增加约束，要么满足定义 1 的受保护去激活，则 `Exec_PCM ⊆ Exec_CADVS`。

**证明**：对离散时间步归纳。设第 k 步 `Exec_PCM,k ⊆ Exec_CADVS,k`。第 k+1 步有两种情况：

- 增加约束：可行集取交集，`Exec_PCM,k+1 = Exec_PCM,k ∩ S_new ⊆ Exec_CADVS,k ⊆ Exec_CADVS,k+1`（CADVS 只增不减时成立；若 CADVS 本身切换，则按 v29 的包含性传递）。
- 受保护去激活：由 `R_i(c)`，在 `Reach(c)` 上被删约束恒不活跃，故 `Exec_PCM,k+1 ∩ Reach(c) = Exec_PCM,k ∩ Reach(c)`；在 `Reach(c)` 外系统不可达，不贡献执行轨迹。因此执行集不扩大，仍包含于 CADVS。

归纳成立。∎

**工程含义**：上下文理解的自由度被严格限制在「更保守」或「可证明等价」的方向；这直接规避了上一轮担心的「跨任务迁移负外部性」——上下文不允许凭空放宽安全约束。

### 引理 33（上下文条件机会约束的可靠性）

**陈述**：设 (A1) 上下文可信集 `C_δ` 满足 `P(c_t ∈ C_δ) ≥ 1−δ_c`；(A2) 对任意 `c ∈ C_δ`，退化模型对真实首次穿越时间随机占优，即 `F_τ^true(s|c) ≤ F_τ^model(s|c)` 对所有 `s` 成立；(A3) PMA-MPC 强制 `max_{c∈C_δ} F_τ^model(H|c) ≤ ε`。则真实失效概率满足 `P(τ ≤ H) ≤ ε + δ_c`。

**证明**：令 `E = {c_t ∈ C_δ}`。由全概率公式，
`P(τ ≤ H) = P(τ ≤ H | E)P(E) + P(τ ≤ H | E^c)P(E^c)`。
在 `E` 上，由 (A2) 与 (A3)，`P(τ ≤ H | c) ≤ F_τ^model(H|c) ≤ ε`；在 `E^c` 上概率至多 1。故
`P(τ ≤ H) ≤ ε·P(E) + 1·P(E^c) ≤ ε + δ_c`。∎

**工程含义**：机会约束的可靠性不是「模型预测准」这种模糊说法，而是两个可验证条件：上下文可信集的覆盖概率、退化模型的随机占优。OOD 时用 `upper_envelope` 正是为了维持 (A2)。

### 引理 34（双时间尺度陈旧性界）

**陈述**：设退化轨迹 `z(t)` 关于时间 `L_z`-Lipschitz，健康指数 `h = 1 − z/z_fail`。若 PDC 在 `t_k` 计算、慢环周期 `Δt_prog ≤ δ_h · z_fail / L_z`，则对任意 `t ∈ [t_k, t_k + Δt_prog]`，用陈旧 PDC 评估的健康指数满足 `|h(t) − h(t_k)| ≤ δ_h`。进一步，若机会约束在 `H + Δt_prog` 上以 `ε` 执行，则真实 `H` 时域失效概率仍不超过 `ε`（在引理 33 的占优假设下）。

**证明**：由 Lipschitz 性，`|z(t) − z(t_k)| ≤ L_z (t − t_k) ≤ L_z Δt_prog`。两边除以 `z_fail` 得健康指数误差界。机会约束部分：`F_τ(H) ≤ F_τ(H + Δt_prog) ≤ ε`，因 `F_τ` 单调不减。∎

**工程含义**：慢环不是「越慢越省算力」，而是有硬性上界：`Δt_prog` 必须与退化速率和健康阈值匹配。磨损越快、`δ_h` 越严，慢环必须越快。

### 引理 35（上下文—退化可辨识性）

**陈述**：考虑线性退化归因模型
`z_t = z_0 + β t + Σ_{c∈C} α_c · t · 1[c_t = c] + ε_t`。
若观测区间内只出现单一上下文 `c_0`，则设计矩阵列 `t` 与 `t·1[c_t=c_0]` 共线，`β` 与 `α_{c_0}` 不可分别辨识，只能辨识其和 `β + α_{c_0}`。反之，若至少出现两个上下文且各自时间支撑不完全重合，设计矩阵满列秩，则 `β` 与 `α_c` 可辨识。

**证明**：设计矩阵 `X = [1, t, {t·1[c_t=c]}]`。单上下文时，对每个样本 `t·1[c_t=c_0] = t`，两列完全相同，`rank(X)` 小于列数，OLS 解不唯一。多上下文且时间支撑不完全重合时，存在样本使 `1[c_t=c_1] ≠ 1[c_t=c_2]`，对应列线性无关；配合截距与 `t` 列，`X` 满列秩，故参数可辨识。∎

**工程含义**：这是本方案最重要的「诚实边界」：**没有上下文激励，就没有上下文理解**。任何声称在单一工况下能高置信区分负载磨损与故障进展的 RUL 模型，都在做不可辨识的外推。CPCM 用 `κ_X` 显式检测这一点，并把下游切换为保守维护。

### 定理（PCM 安全性与执行集收缩）

**陈述**：在以下假设下：
(A1) CC 有效，且上下文可信集覆盖真实上下文（引理 33 的 `C_δ`）；
(A2) PDC 对真实退化随机占优，OOD 时使用保守上界；
(A3) 所有去激活满足定义 1 的受保护条件；
(A4) CPCM 未报告 `degradation_model_drift`；
(A5) PMA-MPC 在 `H + Δt_prog` 上强制机会约束；
则 `Exec_PCM ⊆ Exec_CADVS ⊆ Exec_v29`，且从当前时刻到维护窗口内，非计划失效概率不超过 `ε + δ_c + δ_prog + δ_maint`，其中 `δ_prog` 为慢环陈旧性引入的额外风险，`δ_maint` 为维护执行延迟/失败的概率。

**证明**：

- 执行集包含性由引理 32 直接给出；CADVS 对 v29 的包含性原样继承。
- 失效概率界：由引理 33 得上下文与退化模型误差贡献 `ε + δ_c`；由引理 34 得慢环陈旧性贡献 `δ_prog`；维护执行不确定性贡献 `δ_maint`。四项由并集界合并。∎

**诚实声明**：(A1)–(A5) 在真实部署中并非恒真。上下文可能长期单一（引理 35 的不可辨识），退化模型可能因新工况/新故障模式而 OOD，维护可能被人为推迟。PCM 的工程价值不在于「消除这些假设」，而在于**让每个假设都有对应的运行时证书与降级路径**：CC 失效 → 禁止去激活；PDC OOD → 保守上界；CPCM 漂移 → 加宽 RUL；MACS 被拒 → 强制降额。

### 5.4 关键实验与判定标准

1. **E1（主实验）**：B0–B5 在含上下文切换的退化场景中对比。判定：B3 非计划失效率显著低于 B1（p < 0.05，配对检验），且不必要维护率显著低于 B5。
2. **E2（上下文消融）**：单工况长时运行。判定：B3 应主动报告 `context_not_excited`，并退化为保守维护；若 B3 仍输出高置信 RUL 且未报告不可辨识，则判定为**实现失败**（说明 CPCM 失效）。
3. **E3（OOD 压力）**：注入训练分布外的地形/负载组合。判定：PDC 的 OOD 标志触发率 ≥ 80%，且触发后非计划失效不高于 B1。
4. **E4（实时性）**：快环 500 Hz、慢环 1 Hz 压测，注入 CPU 抢占与通信抖动。判定：快环 P99 额外延迟 < 0.3 ms；慢环不阻塞快环（异步线程/双缓冲）。
5. **E5（硬件在环）**：真实双足平台 20 等效小时，重点观察维护证书被操作员拒绝后的降额行为。

### 5.6 失败判据（可证伪性）

- 若 B3 在有上下文切换时相对 B1 的非计划失效下降 < 15%，则「上下文理解对 PdM 必要」这一核心假设被否定。

- 若 CPCM 误报率 > 5%/小时，则监控不可用，需重新设计阈值。

| R34 | **RUL 模型分布外失效** | **极高** | 1) PIT/CRPS 后验校验；2) OOD 时只输出保守上界；3) CPCM CUSUM 检测模型漂移；4) 定期离线再标定；5) 维护间隔硬上限 | 全新故障模式（训练中从未出现）仍可能被漏检，只能靠硬上限兜底 |
| R35 | **上下文—退化不可辨识（单工况）** | 高 | 1) CPCM 显式计算 `κ_X`；2) 显式报告 `context_not_excited`；3) 下游退化为保守维护；4) 多机器人/多任务数据共享（需解决隐私与分布差异） | 若部署环境天然单一，上下文理解无法提供归因收益，方案退化为 PdM |
| R36 | **快慢环不一致（快环使用陈旧 PDC）** | 中 | 1) 引理 34 的 `Δt_prog` 上界；2) PDC 年龄硬门控；3) 慢环双缓冲/原子切换；4) 机会约束在 `H + Δt_prog` 上执行 | 退化速率突变（如突发冲击损伤）仍可能超出 Lipschitz 假设 |
| R37 | **维护决策振荡 / 操作员拒绝** | 中 | 1) 维护请求迟滞与最小驻留时间；2) 安全运行包络强制降额；3) 可审计日志与人工确认；4) 拒绝后自动收紧 `h_safe` | 长期拒绝维护会持续降额，可用率下降，需管理流程配合 |

## 7. 本轮最大风险（最终确认）

**一句话**：**预测性维护与上下文理解共享同一个不可观测混杂因子——当机器人长期处于单一工况（上下文缺乏激励）时，负载诱导的可逆退化与故障诱导的不可逆退化在统计上不可辨识；系统可能以高置信度把「重载磨损」误判为「健康」或把「早期故障」误判为「工况负载」，从而在最需要维护时签发「未来 H 步安全」的证书。** 这不是预测精度问题，而是**可辨识性缺失下的跨时间尺度虚假安全**，比瞬时证书失效更隐蔽，因为它不会立刻触发违规，却会系统性地推迟正确维护。
