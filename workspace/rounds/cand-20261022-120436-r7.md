# 想法区 · 第 7 轮：从 X-DUB/OL 到 X-DUB/AG*

**灵感词**：A*搜索 / 贪心算法 / 泛化能力  
**起点**：v0.4「X-DUB/OL」。它已经有 AVAIL 异构打包核、PHASE-RANK 窗口排序、证书 bandit 和证明树；本轮不推翻这些，而是补三个更基础的结构性缺口：**搜索没有一致的 f、上界没有便宜的引导、证书不会跨状态/跨截止期泛化**。

## 一句话直觉：把“局部下界”变成“沿路径一致的下界”，再用贪心完成做焦点，用证书泛化减少重复证明

v0.4 的 B&B 是“每次重新算一个局部 LB，然后按 LB 展开”。这有两个后果。第一，父节点已经证过的截止期，子节点可能重新算一遍；如果子节点的局部 LB 反而更低，best-first 会把它当成更有希望的节点，造成重复展开。第二，v0.4 的 anytime 质量主要靠 MCTS/rollout 和 bandit，但第 6 轮的实验已经诚实报告：**廉价特征下的 bandit 只匹配最佳固定顺序，远未达到 oracle**。继续加特征不是本轮的方向。

A* 给我的启发不是“再加一个启发式函数”，而是**一致性（consistency）**：如果每个局部下界都沿搜索树继承，并令

```text
F(child) = max(F(parent), L_loc(child)),
f(σ)     = max(C(σ), F(σ)),
```

那么 `f` 沿每条根到叶的路径单调不减，`h=f-C` 满足 `h(σ) ≤ w(σ,σ') + h(σ')`，其中 `w=C(σ')-C(σ)`。这意味着 A* 不需要 reopening；而且父证书对整棵子树都有效。这个“路径最大值”把 v0.4 的一堆局部证书变成了一个真正一致的 A* 启发式。

贪心算法补的是另一半：v0.4 有可行上界，但没有“从当前状态快速看一眼完成会是什么样”的便宜工具。对每个被展开的节点跑一个小的贪心表调度组合（CP / LPT / MWKR），就得到一条完整可行调度，直接更新 `U`。更重要的是，它的 makespan 可以作为 focal search 的 guide：

```text
f 是可信的下界，决定“哪些节点还值得看”；
Ĝ 是不可信的贪心上界，只决定“在焦点集合里先看谁”。
```

这样既保留了 A* 的可采纳性，又让 anytime 上界快速下降。`Ĝ` 永远不用于剪枝，所以它错得再多也只损失时间。

“泛化能力”在 v0.4 里被理解成 bandit 的统计泛化，但实验失败了。本轮改成**演绎泛化**，分三层：

1. **截止期泛化（THRESH-CERT）**：固定窗口 `(a,b)` 后，强制集 `X_H` 随 `H` 减小而增大；因此“`BP(X_H,caps)` 不可行”对 `H` 是向下封闭的。一次精确测试可以升级成一个阈值 `H*(a,b)`，一张证书覆盖整个区间 `H≤H*`，而不是只证一个 `H`。
2. **路径泛化（CERT-INHERIT）**：祖先的任意绝对下界对后代都有效，因为 `OPT(parent)≤OPT(child)`。父证书可以直接传给子节点，且不会破坏可采纳性。
3. **状态泛化（DOM-GEN）**：同一已调度集 `S` 下，若 `A_σ≤A_τ` 且 `c_σ≤c_τ`，则 `σ` 支配 `τ`，`OPT(σ)≤OPT(τ)`。任何在 `σ` 上有效的下界对 `τ` 也有效；搜索可以直接剪掉 `τ`，并在证明 DAG 里用 `DOMINATED-BY(σ)` 记录见证。

这三层都不需要训练，也不依赖“特征能不能预测成功”。它们把“泛化”从统计口号变成了可检查的局部规则。

## 三个灵感词分别补什么

- **A*搜索**：把 `f` 写成一致的 `max(C,F)`；用 focal search 在 `f` 的容许带内按 guide 选点；证明 focal 的选择不破坏精确性；父证书继承使 best-first 不需要 reopening。
- **贪心算法**：用 CP/LPT/MWKR 三个表调度规则组成贪心组合，既提供可行 `U`，又提供焦点内的 guide。贪心只排序，不剪枝；每条贪心调度都可独立检查为可行。
- **泛化能力**：THRESH-CERT 把点证书泛化成截止期区间；CERT-INHERIT 把证书泛化到整棵子树；DOM-GEN 把证书和状态泛化到被支配状态；可选的 CERT-REGION 进一步把证书泛化到一个由 `lo/q/A` 不等式定义的状态区域。

## 核心方案：X-DUB/AG*

在 v0.4 上做五处增量：

1. **A*-CONSIST**：新状态量
   ```text
   F(root) = L_loc(root)
   F(child) = max(F(parent), L_loc(child))
   f(σ) = max(C(σ), F(σ))
   ```
   其中 `L_loc` 是 v0.4 的 `L0/L_D/L_AV` 加上本轮的 `L_TH`。证明 `F≤OPT`、`f(child)≥f(parent)`、`h=f-C` 一致；因此 best-first 不需要 reopening，父下界对子树有效。

2. **FOCAL-GREEDY**：对每个候选节点惰性计算贪心组合
   ```text
   Ĝ(σ) = min_{π∈{CP,LPT,MWKR}} Cmax(Greedy(σ,π)).
   ```
   `Ĝ` 是可行上界，不是下界。维护焦点集合
   ```text
   Φ_ω = { v∈Open : f(v) ≤ f_min + ω },
   ```
   在 `Φ_ω` 中选 `Ĝ` 最小的节点展开；`ω=0` 退化成“用贪心做 A* 的 tie-break”，`ω>0` 是标准 focal search。任何 guide 选择都不影响剪枝正确性。

3. **THRESH-CERT**：固定窗口 `(a,b)`，用单调二分求
   ```text
   H*(a,b) = max { H : BP(X_H(a,b), caps(a,b)) 不可行 }.
   ```
   一张证书 `(a,b,H*,X,π)` 覆盖所有 `H≤H*`，给出 `L_TH=H*+1`。它把 v0.4 的“在 `H=U-1` 上试一次”升级成“一次找到该窗口能证的最强截止期”。只在根节点/周期扫描时启用，避免每节点多次二分。

4. **DOM-GEN**：同 `S` 状态支配
   ```text
   σ ⪯ τ  iff  sort(A_σ) ≤ sort(A_τ) 且 c_σ,i ≤ c_τ,i (∀i∈S).
   ```
   若 `σ⪯τ`，则 `OPT(σ)≤OPT(τ)`；剪掉 `τ`，并在证明 DAG 里记录 `DOMINATED-BY(σ)`。v0.4 没有跨路径的状态泛化，这是本轮最稳定、实验收益最大的结构项。

5. **PROOF-DAG**：证明树升级成证明 DAG，新增
   - `INHERIT(parent)`：验证 `F(child)≥F(parent)`，父证书有效；
   - `THRESH-CORE(a,b,H*,X,π)`：验证 `H*` 处强制集、异构容量和装箱不可行；由单调性覆盖所有 `H≤H*`；
   - `DOMINATED-BY(σ)`：验证同 `S`、排序后 `A` 与 `c` 的逐分量不等式，且 `σ` 的子树已闭合/下界已达 `U`。
   checker 不信任 focal、guide、阈值二分和 bandit；它只检查每个证书的局部证据。

组合下界：

```text
L_X5(σ) = max( L0(σ), L_D(σ), L_AV(σ;U-1), L_TH(σ) )
F(σ)    = max over path certificates
f(σ)    = max( C(σ), F(σ) )
```

因为 `L_TH` 只增不减、`F` 取路径最大，所以 `F(σ) ≥ L_X4(σ)`；关闭 THRESH 就退回 v0.4 的局部界。关闭 focal、DOM 和 inherit，就得到 v0.4 的 best-first 行为。

## 本轮要验证的命题

1. **OPT 单调**：若 `σ'` 是 `σ` 的后代，则 `OPT(σ)≤OPT(σ')`；因此祖先的绝对下界对后代有效。
2. **A* 一致性**：`F` 可采纳，`f` 沿边单调，`h=f-C` 满足一致性；best-first 不需要 reopening。
3. **Focal 精确**：只要剪枝仍用 `f≥U`，在焦点集合内按任意 guide 选择都不破坏精确性；无限预算下前沿耗尽即 `U=OPT`。
4. **THRESH 可采纳**：固定 `(a,b)`，`X_H` 对 `H` 单调；`H*` 处不可行意味着所有 `H≤H*` 不可行，故 `L_TH≤OPT`。
5. **支配可采纳**：`σ⪯τ ⇒ OPT(σ)≤OPT(τ)`；`σ` 的证书对 `τ` 有效；剪掉 `τ` 不丢更优解。
6. **v0.4 可恢复**：关闭 THRESH/INHERIT/DOM/FOCAL，恢复 v0.4 的搜索语义。
7. **节点数与 anytime 收益**：在 n=9–10、m=2 的 30 个困难随机 DAG 上，`FOCAL+DOM` 的总扩展节点数应显著低于 best-first，且同一节点预算下的间隙更小；所有变体必须返回相同 OPT。
8. **THRESH 的边界**：它只在“截止期/装箱缺口”上有效；若剩余间隙来自优先约束，阈值证书不应被吹成万能药。

## 初步结果与边界

- **实验设置**：从 416 个随机 DAG 中筛出 30 个 best-first 扩展数 ≥20 的困难实例；`n∈{9,10}`，`m=2`，`p∈[1,pmax]`，边概率 0.15–0.45。用独立穷举 DFS 验证全部 30 个实例，30/30 与搜索返回的 OPT 一致；精确 DFS 平均 0.724 秒，最大 12.17 秒。
- **节点数**：best-first 总扩展 2,423；加 DOM 后 1,148（47.4%）；加 focal tie-break 后 886（36.6%）；`FOCAL+DOM` 428（17.7%）。30 个实例上 `FOCAL+DOM` 对 best-first 是 30 胜 0 平 0 负；`FOCAL` 是 26 胜 4 平 0 负。
- **Anytime**：在 25 次扩展预算下，best-first 的平均剩余间隙是 0.933，`FOCAL+DOM` 是 0.033；在 100 次预算下，best-first 只有 23/30 找到 OPT，`FOCAL+DOM` 是 30/30。也就是说，focal 的主要价值是**更早拿到好上界**，而不只是最终少展开几个节点。
- **继承确实在工作**：best-first 生成的子节点中 72.8% 的 `F` 严格大于子节点局部下界；`FOCAL+DOM` 中为 73.5%。消融显示继承把 best-first 的扩展从 2,514 降到 2,423，把 `FOCAL+DOM` 从 600 降到 428。
- **THRESH 收益有限但真实**：40 个随机可达状态上，平均 `L0=27.725`、单点 AVAIL `28.425`、阈值 `28.750`；阈值严格优于单点的有 3/40，优于 `L0` 的有 11/40；平均 16.65 次装箱测试，最多 141 次；命中时平均多覆盖 3.33 个截止期。20 个“贪心上界比 OPT 差 ≥2”的根实例上，阈值没有超过 `L0`——这些间隙来自优先约束，不是打包核。这个负结果很重要：**THRESH 是证书泛化，不是新的万能下界**。
- **Guide 消融**：在 `FOCAL+DOM` 上，只用 CP 得 416 次扩展，LPT 507，MWKR 497，CP+MWKR 405，三者组合 428。特定规则影响不大，收益主要来自“用贪心 guide 选点 + 支配剪枝”，不是某个神奇优先级。
- **边界**：只做了 m=2、n≤10、随机 DAG；没有 PSPLIB、没有 m>2 的精确异构装箱、没有独立 checker 对拍、没有实现完整的证明 DAG checker。focal 与 DOM 的交互、证书区域缓存、跨实例泛化都留到下一轮。

## 本轮的一句话最大风险

**当前方案最大的风险是：A* 一致性与支配剪枝的收益集中在“同一已调度集被多条动作路径到达、且贪心完成与 OPT 相关”的小型随机 DAG 上；在大型 precedence-heavy 实例上，focal 的多次贪心 rollout、支配表和周期阈值二分可能比它们省下的节点更贵，而 THRESH 对真正的优先约束间隙几乎无能为力。**

## 0. 版本关系与本轮增量

v0.4（X-DUB/OL）已经建立：

- `P|prec|Cmax` 的 `(任务,机器)` 动作空间与最优性覆盖；
- 时间价格对偶 `L_D`、指数 B&B、MCTS 上界、证明树；
- AVAIL 异构打包核 `L_AV`：`cap_k(W,σ)=max(0,b-max(a,A_k))`；
- PHASE-RANK 窗口排序；
- 带安全护盾的 CERT-BANDIT（可选控制器）。

v0.5 **不推翻** 这些结论，只做五处增量：

1. **A\*-CONSIST**：引入路径最大下界 `F` 和一致启发式
   `f(σ)=max(C(σ),F(σ))`。父证书对后代有效，best-first 不需要 reopening。
2. **FOCAL-GREEDY**：用 CP/LPT/MWKR 贪心组合给出可行上界和 guide；
   focal search 在 `f` 的容许带内按 guide 选点。guide 不参与剪枝。
3. **THRESH-CERT**：固定窗口后，利用强制集对 `H` 的单调性，
   用二分求最大不可行截止期 `H*`，一张证书覆盖整个区间 `H≤H*`。
4. **DOM-GEN**：同一已调度集下的支配关系；若 `σ⪯τ`，剪掉 `τ`，
   并在证明 DAG 里记录 `DOMINATED-BY(σ)`。
5. **PROOF-DAG**：证明树升级为 DAG，新增 `INHERIT`、`THRESH-CORE`、
   `DOMINATED-BY` 三种局部规则。

关系：

```text
关闭 FOCAL/GREEDY/DOM/INHERIT/THRESH  → v0.4 的 best-first 搜索
只开 THRESH + INHERIT                 → 更强的状态层下界
只开 FOCAL + GREEDY                   → 更好的 anytime 上界
全部打开                              → v0.5 完整算法
```

组合下界：

```text
L_X5(σ) = max( L0(σ), L_D(σ), L_AV(σ;U-1), L_TH(σ) )
F(σ)    = 路径上所有 L_X5 的最大值
f(σ)    = max( C(σ), F(σ) )
```

因为 `L_TH≥L0` 且 `F` 取路径最大，所以 `F(σ)≥v0.4` 的局部 `L_X4(σ)`。
关闭 THRESH 后 `L_X5=L_X4`；关闭 INHERIT 后 `F=L_X5`。

## 1. 问题、符号与复用的旧结论

### 1.1 形式化问题

```text
P | prec | Cmax
```

给定任务集 `V={1,...,n}`、工时 `p_i∈Z_{≥1}`、优先约束 `E⊆V×V`（DAG）、
同构机器数 `m`。调度由开始时间 `s_i` 和机器 `μ_i` 组成，满足：

```text
(i,j) ∈ E  ⇒  s_j ≥ s_i + p_i
μ_i = μ_j  ⇒  [s_i, s_i+p_i) 与 [s_j, s_j+p_j) 不重叠
```

目标 `Cmax=max_i(s_i+p_i)` 最小，最优值记 `OPT`。

### 1.2 符号表（v0.5 新增/重定义）

| 符号 | 含义 |
|---|---|
| `σ=(S,A,c)` | 状态：已调度集、机器可用时间、完成时间 |
| `R=V\S` | 未调度集 |
| `C(σ)=max_k A_k` | 状态已完成的 makespan |
| `OPT(σ)` | 从 `σ` 出发完成所有剩余任务的最小绝对 makespan |
| `lo_i(σ)` | 动态 head：含已调度前驱与剩余前驱链 |
| `q_i(σ)` | 动态 tail：`i` 之后剩余最长路径（不含 `p_i`） |
| `L0(σ)` | `max(C, max_i(lo_i+p_i+q_i), ceil(P(R)/m))` |
| `L_D(σ)` | v0.4 的时间价格对偶下界 |
| `L_AV(σ;H)` | v0.4 的 AVAIL 核下界 |
| `L_TH(σ)` | 阈值证书下界（§5.1） |
| `L_X5(σ)` | `max(L0,L_D,L_AV,L_TH)` |
| `L_loc(σ)` | 当前状态下可计算的 `L_X5` |
| `F(σ)` | 路径最大下界 |
| `f(σ)` | `max(C(σ),F(σ))` |
| `h(σ)` | `f(σ)-C(σ)` |
| `w(σ,σ')` | 边代价 `C(σ')-C(σ)` |
| `U` | 当前 incumbent 上界 |
| `U_G(σ)` | 贪心组合从 `σ` 出发的 makespan |
| `Ĝ(σ)` | focal guide，取 `U_G(σ)` |
| `Φ_ω` | 宽度为 `ω` 的 focal 集合 |
| `H*(a,b)` | 固定窗口 `(a,b)` 的最大不可行截止期 |
| `σ⪯τ` | 状态支配：`σ` 不劣于 `τ` |
| `Reg(κ)` | 证书 `κ` 的有效状态区域 |
| `B_focal` | 每次 focal 选择最多计算 guide 的候选数 |
| `K_dom` | 每个 `S` 的支配表上限 |

### 1.3 复用的 v0.4 结论

以下结论直接继承，不再证明：

- **动作覆盖性**：动作 `(i,k)` 在 `t=max(A_k,max_{j∈pred(i)}c_j)` 开始；
  从根出发的某条动作序列可达到一个最优调度。
- **CP 初始上界**：按 `q_i` 降序的 CP 表调度给出可行 `U_0`，
  且 `U_0≤(2-1/m)OPT`（Graham）。
- **前沿下界**：若 `F_open` 覆盖所有可能优于 `U` 的剩余调度，
  则 `min_{v∈F_open}LB(v)≤OPT`。
- **对偶证书**：`g_H(σ,λ)>0 ⇒ H<OPT(σ)`；`L_D` 可采纳。
- **AVAIL 可采纳**：若 `BP(X_W,caps(W,σ))` 不可行，则不存在
  makespan `≤H` 的完成；`L_AV` 可采纳。
- **证明树**：`TERMINAL/PRUNED/EXACT/EXHAUSTED/PACK-CORE-AVAIL`
  的局部检查规则可靠。

v0.5 只替换/扩展搜索顺序、上界生成和证书泛化；主循环的动作空间与
AVAIL 核保持不变。

## 2. 动机：三个结构性缺口

### 2.1 缺口一：局部 LB 不是一致的 A\* 启发式

v0.4 在每个节点独立计算 `LB(σ)`，best-first 按该值展开。若父节点已经
证过“不存在 `Cmax≤H` 的完成”，子节点仍可能重新计算，并得到一个更低的
局部值。A* 的视角下，这说明 `h` 不一致，搜索可能重复展开已经证明过的
区域，或者把资源花在“局部看起来更好、但父证书已经排除”的节点上。

**例 A（一致性缺口）**：

```text
m=2
父状态 σ：A=(0,5)，局部 L_loc(σ)=10
子状态 σ'：A=(4,5)，局部 L_loc(σ')=8
```

v0.4 中 `f(σ)=10`、`f(σ')=8`，best-first 可能先展开 `σ'`。但 `σ'` 是
`σ` 的后代，父节点已经给出的 10 对 `σ'` 同样有效。v0.5 取

```text
F(σ') = max(F(σ), L_loc(σ')) = max(10,8) = 10
f(σ') = max(C(σ'),F(σ')) = 10.
```

这样 `f` 沿路径单调不减，`h=f-C` 一致，父证书不会在子节点“丢失”。

### 2.2 缺口二：上界没有便宜的引导

v0.4 的 anytime 质量依赖 MCTS rollout 和 CERT-BANDIT。第 6 轮的实验
已经报告：在 600 个混合状态上，LinUCB 的成功率与最佳固定顺序相同，
平均成本还略高（20.9 vs 19.9）；oracle 成本是 3.36。也就是说，
**“选哪个证书”不是主要瓶颈，“当前状态离一个好完成有多远”才是。**
本轮用贪心完成补这个信息：

```text
Greedy(σ,CP/LPT/MWKR) → 一条完整可行调度 → U_G(σ)
```

它比 MCTS rollout 便宜、确定、可独立检查；虽然它不是下界，但作为
focal search 的 guide 足够。

### 2.3 缺口三：证书和状态都是一次性的

v0.4 的 AVAIL 证书只在当前 `(σ,H,W)` 上有效；v0.4 的核搜索也没有
跨路径的状态记忆。于是同一个截止期、同一个强制集、同一组机器容量
可能被反复证明。本轮用三种泛化减少重复：

- **截止期泛化**：固定 `(a,b)` 后，`X_H` 随 `H` 减小而增大，
  不可行性向下封闭；一张证书覆盖 `H≤H*`。
- **路径泛化**：祖先的绝对下界对后代有效；`F` 取路径最大。
- **状态泛化**：同 `S` 下，`A` 和 `c` 逐分量更小的状态支配更大的状态；
  支配者的证书对被发现者有效。

### 2.4 三个灵感词的分工

- **A\*搜索**：一致 `f`、focal search、无 reopening 的 best-first。
- **贪心算法**：贪心组合给出可行 `U` 和 guide；只排序，不剪枝。
- **泛化能力**：THRESH-CERT（截止期区间）、CERT-INHERIT（路径）、
  DOM-GEN（状态支配）、CERT-REGION（可选状态区域）。

## 3. A\* 层：一致的路径最大下界

### 3.1 状态代价与边代价

把状态 `σ` 的已提交时间定义为

```text
g(σ) = C(σ) = max_k A_k.
```

从 `σ` 到子状态 `σ'`（调度一个任务）的边代价定义为

```text
w(σ,σ') = C(σ') - C(σ) ≥ 0.
```

因为调度一个任务只会增加某台机器的可用时间，`C` 不会下降；`g` 沿路径
恰好是边代价之和（望远镜和）。这与经典 A* 的 `g` 不同：这里的“代价”
包含空闲时间，正好是 makespan 的已提交部分。

### 3.2 OPT 的单调性

**引理 1（OPT 沿后代不减）**：若 `σ'` 是 `σ` 的后代，则
`OPT(σ) ≤ OPT(σ')`。

**证明**：从 `σ'` 出发的任意完成，加上从 `σ` 到 `σ'` 的前缀，都是
从 `σ` 出发的合法完成。因此 `σ'` 的可行完成集合是 `σ` 的可行完成
集合的子集；子集上的最小值不小于全集上的最小值。证毕。

**推论 1**：若 `L` 是从 `σ` 出发的任意绝对下界，则 `L` 对 `σ` 的
所有后代也有效。

这个推论是 v0.5 继承层的全部依据。它比“同一个窗口证书在子状态重新
成立”更一般：即使窗口、强制集、机器容量都变了，数值下界仍然有效。

### 3.3 路径最大下界

定义

```text
F(root) = L_loc(root)
F(σ')  = max( F(σ), L_loc(σ') )        σ' 是 σ 的子节点
f(σ)   = max( C(σ), F(σ) )
h(σ)   = f(σ) - C(σ)
```

其中 `L_loc` 是当前可计算的任意可采纳下界（`L0/L_D/L_AV/L_TH` 的 max）。

**引理 2（F 可采纳）**：对任意状态 `σ`，`F(σ) ≤ OPT(σ)`。

**证明**：对路径长度归纳。根节点由 `L_loc(root)≤OPT(root)`。若
`F(σ)≤OPT(σ)`，则子节点满足

```text
F(σ') = max(F(σ), L_loc(σ')) ≤ max(OPT(σ), OPT(σ')) = OPT(σ')，
```

最后一步用引理 1。证毕。

**定理 1（f 沿边单调且一致）**：对任意边 `σ→σ'`，

```text
f(σ') ≥ f(σ),
h(σ) ≤ w(σ,σ') + h(σ').
```

**证明**：`C(σ')≥C(σ)` 且 `F(σ')≥F(σ)`，所以
`f(σ')=max(C(σ'),F(σ')) ≥ max(C(σ),F(σ))=f(σ)`。于是

```text
h(σ) = f(σ)-C(σ)
     ≤ f(σ')-C(σ)
     = (C(σ')-C(σ)) + (f(σ')-C(σ'))
     = w(σ,σ') + h(σ').
```

证毕。

**推论 2**：完整状态（`R=∅`）有 `F(σ)≤C(σ)`，所以 `f(σ)=C(σ)`，
`h(σ)=0`；这正是 A* 的目标条件。

### 3.4 与 best-first / reopening 的关系

- 若只用 `f` 做 best-first，且剪枝条件为 `f(v)≥U`，则 `f` 的单调性
  保证：一旦某个节点的 `f` 达到 `U`，它的整棵子树都不会有更好的完成。
- 由于 `F` 沿路径继承，子节点不会因为局部 LB 变小而“回到”父节点
  已经排除的区域；因此不需要为了同一个截止期重新展开父节点。
- 若实现中使用状态合并（相同 `S/A/c`），不同路径可能携带不同的 `F`；
  取最大值即可，因为每个 `F` 都是有效的绝对下界。取最大只会让搜索更
  保守，不会丢解。
- 严格说，focal search 不按 `f` 全局排序；但 `f` 的单调性仍保证
  前沿的最小 `f` 不会下降，且剪枝只依赖可采纳的 `f`。

### 3.5 与 v0.4 的关系

v0.4 的局部界满足 `L_X4(σ)=max(L0,L_D,L_AV)`。v0.5 的
`L_loc(σ)≥L_X4(σ)`（多了 `L_TH`），且 `F(σ)≥L_loc(σ)`。因此

```text
f_v0.5(σ) ≥ max(C(σ), L_X4(σ)) = f_v0.4(σ).
```

v0.5 并不会比 v0.4 少看见任何可行解；它只可能更早排除。

## 4. 贪心层：可行上界与 focal guide

### 4.1 贪心组合

对状态 `σ` 和优先级规则 `π∈{CP,LPT,MWKR}`，定义
`Greedy(σ,π)`：

```text
1  A' ← A; c' ← c; S' ← S
2  while R'=V\S' ≠ ∅:
3      就绪集 Ready ← { i∈R' : pred(i)⊆S' }
4      按 π 选 i∈Ready：
5          CP   : q_i 最大
6          LPT  : p_i 最大
7          MWKR : i 的剩余后代总工时最大
8      选机器 k 使 max(A'_k, max_{j∈pred(i)} c'_j)+p_i 最小
9      在该机器上最早开始，更新 A'_k,c'_i,S'
10 返回 max_k A'_k
```

三条规则分别偏向关键路径、长任务和“下游工作量大”的任务。
令

```text
U_G(σ) = min_{π∈{CP,LPT,MWKR}} Cmax(Greedy(σ,π)).
```

**引理 3（贪心调度可行）**：`Greedy(σ,π)` 返回的调度是从 `σ` 出发的
合法完成，且其 makespan 是 `OPT(σ)` 的可行上界。

**证明**：每步只选就绪任务，开始时间不早于所有前驱完成时间和机器
可用时间；同一机器上的任务按开始时间串行执行，不重叠。因此它是合法
调度。任何合法调度的 makespan 都不小于 `OPT(σ)`，所以
`U_G(σ)≥OPT(σ)`。证毕。

### 4.2 为什么 guide 不能用于剪枝

`U_G(σ)` 是上界，不是下界。即使 `U_G(σ)≥U`，也不能推出
`OPT(σ)≥U`：贪心只是“找到了一条不优于 `U` 的调度”，并不排除更好
的调度。因此：

```text
f 用于剪枝（可采纳）；
Ĝ 只用于排序（不可采纳）。
```

这是 v0.5 与“加权 A*”最重要的区别：加权 A* 用不可采纳启发式剪枝，
会损失最优性；v0.5 只把它放在 focal 的 tie-break 里。

### 4.3 Focal search

设

```text
f_min = min_{v∈Open} f(v)
Φ_ω = { v∈Open : f(v) ≤ f_min + ω }.
```

选择

```text
v = argmin_{v∈Φ_ω} Ĝ(v),
```

其中 `Ĝ(v)` 惰性计算并缓存；每次最多计算 `B_focal` 个候选的 guide。
`ω=0` 时是“用贪心做 A* 的 tie-break”；`ω>0` 是标准 focal search。
若 `B_focal` 截断了候选集，被截掉的节点仍留在 `Open`，未来仍可能被
展开；这只影响 anytime 质量，不影响正确性。

### 4.4 Focal 的精确性

**定理 2（Focal 选择安全）**：只要剪枝仍使用可采纳的 `f` 和
`f(v)≥U`，在 `Φ_ω` 内按任意 guide 选择都不破坏精确性。若预算无限，
算法终止时 `U=OPT`。

**证明**：设当前 `U` 是一个可行上界，且 `OPT<U`。取一条从根到最优
完成的最优路径；由引理 2，路径上每个节点 `v` 满足
`f(v)≤OPT<U`。假设算法在未展开该路径的某个节点时终止。终止只能是
`Open=∅` 或 `f_min≥U`。但该路径上第一个未展开节点的父节点已展开，
所以它已被生成；由于 `f<U`，它没有被 `f` 剪枝；若它被支配剪枝，
由 §5.4 的支配引理会有一个不劣的状态覆盖它。因此它或它的支配者在
`Open` 中，且 `f≤OPT<U`，与 `f_min≥U` 矛盾。故算法必须继续展开，
直到达到一个完整状态；该状态的 `C≤OPT`，结合 `U≥OPT` 得到
`U=OPT`。guide 的选择只改变“先展开哪个”，不改变上述集合的有限性
和剪枝条件。证毕。

**备注**：若同时使用支配剪枝，定理 2 的“路径节点仍在 Open”要用
支配引理替换为“存在一个不劣的支配者”；细节见 §5.4。focal 的
guide 可以为空/损坏，最坏情况退化成任意选择，仍不会错。

### 4.5 Anytime 解释

每次展开节点 `v` 时计算 `U_G(v)`，并把 `U` 更新为
`min(U,U_G(v))`。因此：

- 每展开一个节点，至少得到一条新的可行调度（不一定更好）；
- 在 focal 选择中，`Ĝ` 小的节点优先展开，通常更早得到好的 `U`；
- 失败/剪枝不会降低 `U`；
- 任意时刻 `L≤OPT≤U`，其中 `L` 由全局根证书和 `min_{Open}f` 给出。

## 5. 泛化层

### 5.1 THRESH-CERT：把点证书泛化成截止期区间

固定状态 `σ`、窗口 `W=[a,b)` 和容量向量
`caps_k=max(0,b-max(a,A_k))`。对截止期 `H` 定义

```text
X_H(a,b) = { i∈R : lo_i≥a, H-q_i≤b }.
```

**引理 4（强制集单调）**：若 `H'≤H`，则 `X_{H'}⊇X_H`。

**证明**：`H'≤H` 蕴含 `H'-q_i≤H-q_i`；满足 `H-q_i≤b` 的任务也满足
`H'-q_i≤b`。`lo_i≥a` 与 `H` 无关。证毕。

**引理 5（装箱不可行的向下封闭）**：若 `BP(X_H,caps)` 不可行，且
`H'≤H`，则 `BP(X_{H'},caps)` 也不可行。

**证明**：`X_{H'}⊇X_H`；装箱不可行性对超集单调（若超集可行，则其
子集 `X_H` 也可行，矛盾）。证毕。

定义

```text
P_σ(a,b) = { H≥L0(σ) : BP(X_H(a,b),caps(a,b)) 不可行 }
H*(a,b)  = max P_σ(a,b)        （若 P 为空则不存在）
L_TH(σ)  = max( L0(σ), max_{a,b} (H*(a,b)+1) ).
```

**定理 3（THRESH 可采纳）**：若 `H*(a,b)` 存在，则
`OPT(σ) ≥ H*(a,b)+1`；因此 `L_TH(σ)≤OPT(σ)`。

**证明**：由 `H*` 的定义，`BP(X_{H*},caps)` 不可行；由定理 1
（AVAIL 可采纳），不存在从 `σ` 出发、makespan `≤H*` 的完成。
由于 makespan 是整数，`OPT(σ)≥H*+1`。对窗口取 max、与 `L0` 取 max
仍不超过 `OPT`。证毕。

**算法**：对每个候选 `(a,b)`，在 `[L0,U-1]` 上二分最大不可行 `H`。
谓词 `BP(X_H,caps)` 由引理 5 单调，二分合法。候选窗口取 v0.4 的
事件集合

```text
{0,U-1} ∪ {lo_i} ∪ {(U-1)-q_i}
```

生成的所有 `a<b` 对；也可以加入 PHASE-RANK 的前若干个窗口。扫描不
完整只影响 `L_TH` 的强度，不影响正确性。

**成本**：每个窗口 `O(log(U-L0))` 次装箱测试；设窗口数 `W=O(n²)`，
单次测试 `T_BP`，则
`T_TH=O(W log(U-L0) T_BP)`。因此只在根节点和每 `T_scan` 次扩展时
运行；内部节点默认只在 `H=U-1` 上做一次便宜的 AVAIL 测试。

**与 v0.4 的关系**：v0.4 的 `PACK-CORE-AVAIL` 是
`THRESH-CORE` 在 `H*=H` 时的特例。阈值证书多出来的是“同一窗口覆盖
更低的截止期”，因此可以在 anytime 中把 `L` 推得更高，而不必对每个
`H` 重复构造证书。

### 5.2 CERT-INHERIT：路径泛化

由引理 1，根/祖先的任意绝对下界对后代有效。实现上：

- 每个节点存储 `F`（父证书和局部证书的最大值）；
- 子节点生成时先继承 `F(parent)`，再与 `L_loc(child)` 取 max；
- 证明 DAG 中加一条 `INHERIT(parent)` 链接，checker 验证
  `F(child)≥F(parent)` 且父节点的证书有效；
- 若父节点的证书是在旧 `U` 下得到的，它仍然有效；`U` 下降不会使
  旧的下界失效。

**引理 6（继承安全）**：若 `F(parent)≤OPT(parent)`，则
`F(parent)≤OPT(child)`。

**证明**：引理 1。证毕。

**注意**：继承的是**数值下界**，不是“同一个窗口在子状态仍然成立”。
子状态的 `lo/q/A` 可以变化，但只要父下界是绝对 makespan 下界，它就
对后代有效。这一点比 v0.4 的局部窗口复用更强。

### 5.3 CERT-REGION：可选的跨状态泛化

设 `κ=(a,b,H*,X,π)` 是在状态 `σ0` 上验证过的阈值证书。定义它的
有效区域：

```text
Reg(κ) = { σ' :
    X⊆R(σ'),
    ∀i∈X: lo_i(σ')≥a 且 H*-q_i(σ')≤b,
    ∀k: A'_k≥A_k(σ0) }.
```

**引理 7（区域泛化）**：若 `σ'∈Reg(κ)`，则 `H*` 对 `σ'` 也不可行，
即 `OPT(σ')≥H*+1`。

**证明**：条件保证 `X` 在 `σ'` 中仍被强制在窗口 `[a,b)` 内；
`A'_k≥A_k(σ0)` 使 `caps'_k≤caps_k`；容量变小只会让装箱更难，所以
`BP(X,caps')` 仍不可行。由定理 1，`H*` 不可行。证毕。

**用途**：可以把已验证的证书按 `(a,b,H*,X)` 缓存；新状态先做
`O(|X|+m)` 的区域检查，命中就复用 `H*+1`，不必重跑子集和。
区域检查失败时再走正常的 AVAIL/THRESH。该层是可选的；本轮实验
没有实现缓存，只把它作为证明系统中的一条可检查规则。

### 5.4 DOM-GEN：状态支配

固定同一个已调度集 `S`。对两个状态 `σ,τ`（`S_σ=S_τ=S`）定义

```text
σ ⪯ τ   iff
    sort(A_σ) ≤ sort(A_τ)   逐分量
且  c_σ,i ≤ c_τ,i            ∀i∈S.
```

机器同构，所以 `A` 排序后比较；`c_i` 是任务完成时间，与机器标签无关。

**引理 8（支配保序）**：若 `σ⪯τ`，则 `OPT(σ)≤OPT(τ)`。

**证明**：把 `τ` 的任意完成调度按同样的任务顺序搬到 `σ` 上。因为
`A_σ` 排序后逐分量不大于 `A_τ`，可以重标号机器，使每个任务的机器
可用时间不晚于 `τ`；又因为 `c_σ,i≤c_τ,i`，每个任务的前驱完成时间
也不晚于 `τ`。归纳每个动作，`σ` 上的对应开始时间不晚于 `τ`，所以
完成时间不晚于 `τ`。因此 `OPT(σ)≤OPT(τ)`。证毕。

**推论 3（证书转移）**：若 `σ⪯τ`，则任何在 `σ` 上有效的绝对下界
在 `τ` 上也有效。注意方向：**从支配者（更好）流向被支配者（更差）**，
反过来不成立。

**搜索规则**：

- 对每个 `S` 维护一张支配表（Pareto 前沿）；
- 新状态 `τ` 生成时，若存在表中 `σ` 使 `σ⪯τ`，剪掉 `τ`，记录
  `DOMINATED-BY(σ)`；
- 若新状态支配表中已有状态，可惰性标记旧状态为不活跃；由于支配关系
  传递，旧状态的支配者也覆盖新状态的被支配者；
- 表大小超过 `K_dom` 时停止插入/只做哈希去重，避免内存爆炸；
- 相同状态（双向支配）用规范键 `(S,sort(A),c)` 做 transposition，
  不产生 `DOMINATED-BY` 环。

**与 anytime 的交互**：支配剪枝不会丢失最优解，但可能丢掉被支配状态
上的一条**好的贪心调度**。因此在剪掉 `τ` 之前，可选地先计算
`U_G(τ)` 并更新 `U`；这把“可能失去的 incumbent”变成一次 `O(T_G)`
的贪心调用。若追求速度，也可以跳过，只影响 anytime 质量。

### 5.5 泛化层的总结

| 层 | 泛化对象 | 规则 | 是否需要训练 |
|---|---|---|---|
| `THRESH-CERT` | 截止期 `H` | 固定窗口，`H≤H*` 全不可行 | 否 |
| `CERT-INHERIT` | 搜索路径 | 祖先下界对后代有效 | 否 |
| `CERT-REGION` | 状态区域 | `lo/q/A` 不等式区域 | 否 |
| `DOM-GEN` | 同 `S` 状态 | `A`/`c` 逐分量支配 | 否 |

这与 v0.4 的 `CERT-BANDIT` 形成对照：bandit 需要从数据中估计
“哪个 arm 会成功”，在廉价特征下没有超过最佳固定顺序；本轮的泛化
是演绎的、可检查的，不依赖特征质量。

## 6. 主循环 X-DUB/AG\*

```text
算法 X-DUB/AG*(G,p,m,B)
────────────────────────────────────────────────
1  (lo,q,L0) ← PRECOMPUTE(G,p,m)
2  π0,U0 ← CP-LIST-SCHEDULE(G,p,m)
3  best ← (U0,π0);  U ← U0
4  root ← NEW-NODE(σ0=(∅,0^m,⊥))
5  root.L ← L_LOC(root,U)
6  root.F ← root.L;  root.f ← max(C(root),root.F)
7  Open ← {root};  DomTable ← {(S=∅): [(sort(A),c,root.id)]}
8  F_global ← -∞;  t ← 0
9  while Open ≠ ∅ and t < B:
10     purge Open 中 f≥U 的节点
11     if Open=∅: break
12     f_min ← min_{v∈Open} f(v)
13     if f_min≥U: break
14     if FOCAL:
15         Φ ← {v∈Open : f(v)≤f_min+ω}
16         v ← argmin_{v∈Φ, |Φ|≤B_focal} GUIDE(v)
17     else:
18         v ← argmin_{v∈Open} f(v)
19     if DOMINATED(v):
20         U ← min(U,GUIDE(v))        # 可选：保留其贪心上界
21         record DOMINATED-BY(witness);  continue
22     t ← t+1
23     U ← min(U,GUIDE(v))
24     for each child w of v:
25         if w is complete:
26             U ← min(U,C(w));  continue
27         L_w ← L_LOC(w,U)           # L0 + AVAIL at U-1 (+ 可选 THRESH)
28         F_w ← max(v.F,L_w)
29         f_w ← max(C(w),F_w)
30         if f_w≥U: prune; continue
31         if DOMINATED(w):
32             U ← min(U,GUIDE(w))    # 可选
33             record DOMINATED-BY(witness);  continue
34         insert w into Open;  update DomTable
35     if t mod T_scan = 0:
36         L_root ← THRESH(root,U)
37         F_global ← max(F_global,L_root)
38         for v∈Open: F(v)←max(F(v),F_global); f(v)←max(C(v),F(v))
39     L ← max(L_ROOT_GLOBAL, min_{v∈Open} f(v))
40 end while
41 if Open=∅ or L≥U:
42     PROOF ← BUILD-PROOF-DAG(root,U)
43 return best,L,U,gap=(U-L)/max(1,L),PROOF
```

其中：

```text
L_LOC(σ,U) = max( L0(σ), L_D(σ), AVAIL(σ,U-1),
                  THRESH(σ) 若启用，否则 -∞ )
```

- `AVAIL(σ,U-1)` 只检查截止期 `U-1`；若成功，返回 `U`，直接剪枝。
- `THRESH(σ)` 在根节点/周期扫描时计算；内部节点默认不跑，除非
  `AVAIL` 命中或 `t mod T_scan=0`。
- `GUIDE(v)` 惰性计算 `U_G(v)`；若返回一条完整调度，更新 `U`。
  focal 候选的 guide 计算也可以更新 `U`；任何贪心调度都是可行上界。
- `DOMINATED(v)` 查 `DomTable`；相同状态用规范键去重。
- `F_global` 是根节点证书给出的全局下界；由引理 1，它对所有节点有效，
  所以可以统一抬高前沿的 `F`。
- `L_ROOT_GLOBAL` 是当前已知的全局根下界；`L` 还取前沿最小 `f`。

**与 v0.4 的差异**：

- v0.4 在每个节点独立算 `LB`；v0.5 强制继承 `F`。
- v0.4 的 MCTS/bandit 可以被关闭；v0.5 的 guide 是确定性的贪心组合。
- v0.5 多了 `THRESH` 和 `DOM` 两个可关闭层；主循环骨架不变。

## 7. 证明 DAG 与 checker

### 7.1 节点类型

在 v0.4 的节点类型上新增：

```text
INHERIT(parent)
THRESH-CORE(H*, a, b, X, π)
DOMINATED-BY(σ)
```

- `INHERIT`：子节点的 `F` 包含父节点的 `F`；
- `THRESH-CORE`：固定窗口的阈值装箱证书；
- `DOMINATED-BY`：被支配状态的见证。

### 7.2 checker 规则

```text
CHECK-NODE(v):
1  if v in memo: return memo[v]
2  case v.type:
3    TERMINAL:
4        验证 v 附带完整调度；所有任务恰好一次；前驱/机器约束成立；
5        Cmax(v) ≥ U
6    PRUNED-DUAL:
7        验证 v 的对偶证书 g_H(σ,λ)>0
8    PACK-CORE-AVAIL:
9        按 v0.4 规则验证 (H,a,b,X,π)
10   THRESH-CORE(H*,a,b,X,π):
11       验证 H* ≥ L0(v)
12       从 σ_v 和原 DAG 重算 lo,q,A
13       for i∈X:
14           验证 i∈R(σ_v)
15           验证 lo_i ≥ a
16           验证 H*-q_i ≤ b
17       caps_k ← max(0,b-max(a,A_k))
18       验证 π ∈ {TRIVIAL,AGG,DFF,SUBSET,PACK-BB}
19       按 π 验证 BP(X,caps) 不可行
20       # 由引理 4/5，所有 H≤H* 自动不可行；无需枚举
21       若该节点用于剪枝，验证 H*+1 ≥ U（或与其它下界组合后 ≥U）
22   INHERIT(parent):
23       验证 F(v) ≥ F(parent)
24       return CHECK-NODE(parent)
25   DOMINATED-BY(τ):
26       验证 S_v=S_τ
27       验证 sort(A_τ) ≤ sort(A_v) 逐分量
28       验证 c_τ,i ≤ c_v,i (∀i∈S_v)
29       验证 CHECK-NODE(τ)
30       验证 (LB(τ)≥U) 或 (τ 的子树已闭合)
31   EXACT/EXHAUSTED:
32       按 v0.4 规则递归检查所有动作/子节点
33   else: reject
34   memo[v] ← true; return true
```

**DAG 条件**：`DOMINATED-BY` 和 `INHERIT` 可能产生共享子证明；checker
用 `memo` 检测重复，并在进入时维护递归栈，拒绝环。严格支配关系是
偏序，不会成环；相同状态的 transposition 在构造时合并成一个节点，
不产生自环。

### 7.3 可靠性

**定理 4（证明 DAG 可靠）**：若 `CHECK(root)` 通过，则 `U=OPT`。

**证明**：对 DAG 做拓扑归纳。

- `TERMINAL`：附带调度可行，故 `OPT≤U`。
- `PRUNED-DUAL`：对偶引理给出该状态没有 `Cmax<U` 的完成。
- `PACK-CORE-AVAIL`：v0.4 定理 1。
- `THRESH-CORE`：定理 3；`H*` 处不可行，且 `H*≥U-1` 时直接排除
  `Cmax<U`；若 `H*<U-1`，它只贡献下界，不单独闭合根，但子证明会
  与其它节点组合。
- `INHERIT`：父下界有效，子 `F` 不小于父 `F`，故子下界有效。
- `DOMINATED-BY`：由引理 8，`OPT(τ)≥OPT(σ)`；若 `LB(σ)≥U` 或 `σ`
  的子树闭合，则 `τ` 也没有 `Cmax<U` 的完成。
- `EXACT/EXHAUSTED`：所有动作/子节点覆盖，归纳假设给出每个子节点
  没有更好的完成；根因此没有 `Cmax<U` 的完成。

结合 `U` 来自可行调度，`U=OPT`。证毕。

### 7.4 独立性

- `lo/q/A` 由 checker 从 `σ` 和原 DAG 重新计算，不信任搜索器缓存；
- `X` 的强制性逐项验证；
- `caps` 由 checker 重算；
- 阈值二分、focal 选择、guide、bandit 都不在证明 DAG 里；
- `DOMINATED-BY` 的见证状态必须在 DAG 中有一个已检查的证明；
- `THRESH-CORE` 的区间性质由引理 4/5 保证，不需要为每个 `H` 附一份
  子集和证据。

### 定理 5（任意时刻区间）

在 `X-DUB/AG*` 运行的任意时刻，

```text
L ≤ OPT ≤ U.
```

**证明**：`U` 来自 CP 或贪心/rollout 的可行调度，故 `OPT≤U`。`L` 是
`L0`、`L_ROOT_GLOBAL`、前沿 `min f` 的最大值；`L0` 和根证书由引理 2/3
可采纳，前沿 `f` 由路径继承和局部可采纳性给出 `f(v)≤OPT(v)`；前沿
覆盖性给出 `min_v f(v)≤OPT`。因此 `L≤OPT`。证毕。

### 定理 6（终止即最优）

若算法因 `Open=∅` 或 `L≥U` 终止，则 `U=OPT`。

**证明**：若存在 `Cmax<U` 的完成，由动作覆盖性和前沿覆盖性，它必须
经过某个开节点 `v`，且 `f(v)≤Cmax<U`。这与 `Open=∅` 或
`min_{v∈Open}f(v)≥U` 矛盾。结合 `U` 可行，`U=OPT`。证毕。

### 定理 7（有限完备性）

搜索树有限；每次 BBF 展开前进一个任务；focal 可能延迟但不会无限
跳过可展开节点；支配/证书剪枝只删除没有更优完成的状态。预算无限时
前沿最终为空或 `f_min≥U`。最坏时间复杂度仍指数；这是 NP-hard 问题
的预期行为。

### 与 v0.4 的支配关系

```text
L_X5(σ) ≥ L_X4(σ)
F(σ)    ≥ L_X5(σ)
f_v0.5(σ) ≥ f_v0.4(σ)
```

因此 v0.5 的节点下界逐点支配 v0.4；关闭 `THRESH/INHERIT/DOM/FOCAL`
后恢复 v0.4 的搜索语义（除实现细节外）。

## 9. 复杂度分析

### 9.1 单次操作

- **预处理**：拓扑排序 + head/tail，`O(n+|E|)`。
- **`L0`**：`O(n+|E|)`。
- **AVAIL 窗口**：`O(n³)` 朴素（`O(n²)` 窗口 × `O(n)` 强制集），
  可用二维前缀/排序降到 `O(n²)`；记 `T_win(n)`。
- **m=2 精确装箱**：bitset `O(|X|·C/word)`；小核可用 MITM。
- **THRESH**：`O(W log(U-L0) T_BP)`，`W=O(n²)`；只在根/周期启用。
- **贪心组合**：每条约 `O(n(n+|E|))`（每步重算 head/tail）；三条
  规则为常数因子。可用增量 head/tail 降到 `O(n log n+|E|)`，本轮
  未做。
- **focal 选择**：扫描 `Open` 为 `O(|Open|)`；guide 计算最多
  `B_focal` 次，`O(B_focal·T_G)`。
- **支配检查**：每个 `S` 的 Pareto 表大小 `|D_S|`；单次
  `O(|D_S|(n+m))`，受 `K_dom` 限制。
- **证明 DAG 检查**：`O(N_proof+|E_proof|)`。

### 9.2 总复杂度

设 `N` 为物化节点数、`B` 为预算：

```text
时间: O( N·(T_win + T_AVAIL + T_G) + B·T_G·B_focal
        + N·K_dom·(n+m) + T_TH(root) )
空间: O( N(n+m) + Σ_S |D_S|(n+m) + N_proof )
```

最坏情况：

```text
N = O((m·n)^n)
T_AVAIL = O(T_win + |X|·C/word)       # m=2
```

- v0.5 没有改变最坏复杂度；它是“更强的下界 + 更好的顺序 + 更少的
  重复状态”，不是新的多项式算法。
- `T_G` 与 `B_focal` 是主要常数开销；在 n≤15 时可接受，n 很大时
  需要增量贪心和 guide 缓存。
- `K_dom` 控制支配表内存；超过上限后退化为哈希去重，正确性不变。

### 9.3 成本控制

- guide 只对 focal 候选惰性计算，最多 `B_focal` 个；
- THRESH 只在根/`T_scan` 周期运行；
- 内部节点的 AVAIL 只在 `H=U-1` 上做一次；
- 支配表按 `S` 分桶，超过 `K_dom` 停止插入；
- 证明 DAG 只在终止时构造，checker 与搜索器隔离。

## 10. 实验设计与本轮结果

### 10.1 设置

- 随机 DAG：任务按索引拓扑排序；`i<j` 以概率 `ep` 加边；
  `p_i` 均匀取 `1..pmax`；`m=2`。
- 候选池 416 个实例；用 best-first（`L0+AVAIL`）跑一遍，保留扩展数
  在 `[20,1500]` 的 30 个困难实例。`n∈{9,10}`，`ep∈[0.15,0.45]`，
  `pmax∈{5,8,10,15}`。
- 搜索：动作 `(i,k)`，最早开始，机器结果去重；下界为
  `L0+AVAIL(H=U-1)`（m=2 精确子集和）；未启用对偶，以隔离本轮
  变量。
- 贪心 guide：CP/LPT/MWKR 三条表调度规则；`B_focal=32`；focal
  宽度 `ω=2`；支配表按 `S` 维护 Pareto 列表；`inherit=True`。
- 精确验证：独立穷举 DFS（无下界、无支配）计算 OPT；30/30 与搜索
  返回值一致；平均 0.724 秒，最大 12.17 秒，总 21.72 秒。
- 时间：纯 Python，单线程，单次测量；只用于相对 sanity check。

### 10.2 节点数

| 变体 | 总扩展 | 均值 | 中位数 | 贪心调用 | 时间 (s) |
|---|---:|---:|---:|---:|---:|
| best-first | 2,423 | 80.8 | 40.5 | 2,423 | 0.859 |
| best-first + DOM | 1,148 | 38.3 | 26.5 | 1,148 | 0.492 |
| FOCAL（ω=2；ω=0/4 扩展数相同） | 886 | 29.5 | 12.5 | 1,288 | 0.407 |
| FOCAL + DOM | 428 | 14.3 | 11.0 | 763 | 0.266 |

- `FOCAL+DOM` 对 best-first：30 胜 0 平 0 负；总扩展降至 17.7%，
  时间降至 31.0%。
- `FOCAL` 对 best-first：26 胜 4 平 0 负；总扩展降至 36.6%。
- `best-first+DOM`：28 胜 1 平 1 负；总扩展降至 47.4%。
- 所有变体返回同一 OPT（30/30 与独立 DFS 一致）。
- `ω∈{0,2,4}` 在这批实例上给出相同的扩展数；整数 `f` 和候选截断
  使宽度不敏感。本轮不声称 `ω` 调参有收益。

### 10.3 Anytime

表中每个单元格是“平均剩余间隙 / 找到 OPT 的实例数”，间隙为
`max(0,U_best-OPT)`，在固定扩展预算处截取。

| 变体 | 10 次 | 25 次 | 50 次 | 100 次 |
|---|---:|---:|---:|---:|
| best-first | 1.267 / 6 | 0.933 / 11 | 0.400 / 20 | 0.300 / 23 |
| best-first + DOM | 1.233 / 7 | 0.600 / 15 | 0.200 / 24 | 0.067 / 28 |
| FOCAL | 0.567 / 19 | 0.100 / 27 | 0.033 / 29 | 0.033 / 29 |
| FOCAL + DOM | 0.500 / 21 | 0.033 / 29 | 0.033 / 29 | 0.000 / 30 |

**解读**：

- focal 的主要优势是**早**：25 次扩展时已有 29/30 找到 OPT，而
  best-first 只有 11/30；这说明贪心 guide 确实把“看起来快完成”的
  节点排到了前面。
- 最终节点数上，`FOCAL+DOM` 也最好；但这不保证在所有实例上都如此，
  见风险 1。
- `best-first+DOM` 的 anytime 也比 best-first 好，说明支配剪枝不仅
  减少节点，还能让搜索更快集中在有希望的路径上。

### 10.4 继承消融

| 变体 | inherit=False | inherit=True | 子节点继承命中率 |
|---|---:|---:|---:|
| best-first | 2,514 | 2,423 | 3,538 / 4,863 = 72.8% |
| FOCAL + DOM | 600 | 428 | 695 / 946 = 73.5% |

- “继承命中”指生成的子节点中 `F(parent)>L_loc(child)` 的比例；约
  四分之三的子节点实际用到了父证书。
- 继承对 best-first 只减少 3.6% 扩展，但对 `FOCAL+DOM` 减少 28.7%；
  原因是 focal 的 guide 会改变 `U` 的下降轨迹，继承让部分节点更早
  被剪掉。这个交互是小样本观察，不外推。

### 10.5 阈值证书

**40 个随机可达状态**（n=8–9，m=2，随机前缀调度，U 由贪心给出；
OPT 由独立 DFS 计算）：

| 指标 | 值 |
|---|---:|
| 平均 `L0` | 27.725 |
| 平均单点 AVAIL（`H=U-1`） | 28.425 |
| 平均 THRESH | 28.750 |
| THRESH 严格优于单点 | 3 / 40 |
| THRESH 严格优于 `L0` | 11 / 40 |
| 平均装箱测试次数 | 16.65 |
| 最大装箱测试次数 | 141 |
| 命中时平均覆盖的截止期数 | 3.33 |

- 40/40 满足 `THRESH≤OPT`（无假证书）。
- 阈值确实能把“点证书”扩展成“区间证书”，但平均只比单点多 0.325
  个时间单位；它不是本轮的主要性能来源。

**20 个“贪心 U 比 OPT 差 ≥2”的根实例**（n=7–8）：

| 指标 | 值 |
|---|---:|
| 平均 OPT | 56.7 |
| 平均贪心 U | 59.7 |
| 平均 `L0` / 单点 / THRESH | 56.5 / 56.5 / 56.5 |
| `L0=OPT` 的实例 | 16 / 20 |
| 剩余 4 个的 `L0` | `OPT-1` |
| THRESH 闭合剩余 4 个 | 0 / 4 |

**解读**：这些根实例的剩余间隙来自优先约束和机器分配，不是
“窗口内强制集装不下”。THRESH 只对打包/截止期缺口有效；把它宣传成
通用下界会是过度声明。这个负结果与 v0.4 的相变分析一致：稠密 DAG
的核往往太松，真正的冲突在顺序。

### 10.6 Guide 消融

在 `FOCAL+DOM` 上，固定其他设置，只改贪心规则：

| Guide 规则 | 总扩展 |
|---|---:|
| CP | 416 |
| LPT | 507 |
| MWKR | 497 |
| CP + LPT | 449 |
| CP + MWKR | 405 |
| LPT + MWKR | 533 |
| CP + LPT + MWKR | 428 |

- 三条规则组合不是最优（CP+MWKR 405 略好），但差异只有约 5%；
  这说明**guide 的具体规则不是主要矛盾**，真正起作用的是“有一个
  与完成时间相关的 guide”以及支配/A* 层。
- 本轮仍保留三条组合，因为它在不同 DAG 密度上更稳健；不声称
  portfolio 本身是贡献。

### 10.7 正确性与边界

- **精确性**：30/30 实例的最优值与独立 DFS 一致；所有变体的
  `U` 相同。
- **下界安全**：40/40 状态的 THRESH 不超过 OPT；搜索过程中没有出现
  `L>OPT`（按构造和实验检查）。
- **规模**：n=9–10、m=2；这是“机制验证”，不是 benchmark。
- **未做**：PSPLIB/fork-join、n≥20 的 anytime 曲线、m>2 的精确
  异构装箱、独立 checker 对拍、证明 DAG 的实际构造与检查、证书区域
  缓存、跨实例泛化。

### 10.8 下一轮协议

**P1（证明 DAG checker）**：独立实现 `CHECK-NODE`，与搜索器隔离；
500 个 `n≤9`、`m∈{2,3}` 的随机实例；目标零假证书。

**P2（m>2 精确异构装箱）**：实现 `PACK-BB` 和 checker；测
`m=3,4` 上 AGG/DFF/PACK-BB 的覆盖率和证书大小。

**P3（规模与 anytime）**：`n=15..40`，`m=2,3`；PSPLIB/fork-join；
比较 v0.4、v0.5-no-focal、v0.5-no-dom、v0.5 完整的节点数、wall-clock
和 anytime 曲线。

**P4（支配表/证书区域）**：测 `K_dom` 和 `Reg(κ)` 缓存在大规模下的
命中率、内存和收益；若表爆炸，改为按 `S` 的哈希分桶。

**P5（guide 学习）**：在 `THRESH`/`DOM` 固定后，比较 CP/LPT/MWKR、

## 11. 已知风险

1. **Guide 质量与成本**：`Ĝ` 是上界，不是下界；如果它与 `OPT` 相关性
   差，focal 可能先展开“贪心看起来好、实际很差”的节点，增加扩展。
   缓解：`B_focal` 截断；guide 只排序；可退回 `ω=0` 或 best-first。

2. **Focal 不保证更少节点**：本轮的 30 个实例上 `FOCAL+DOM` 全胜，
   但这是筛选过的困难小实例；在 precedence-heavy 大实例上，多次贪心
   rollout 可能比省下的节点更贵。缓解：增量贪心、缓存、按预算禁用。

3. **A* 一致性的前提**：引理 1 依赖“状态是前缀、目标是绝对
   makespan”。若加入 release time、机器非同一、或允许抢占，OPT 的
   单调性/边代价定义需要重新推导。缓解：明确边界；不要直接套用。

4. **支配表的规模**：同 `S` 的 Pareto 前沿可能指数增长；`K_dom`
   截断后只保留部分支配，正确性不变但收益下降。大规模下需要哈希
   分桶/近似支配。

5. **支配只对同一 `S` 有效**：不同已调度集之间没有本轮的支配关系；
   不能把“少调度一个任务”的状态直接与“多调度一个任务”的状态比较。
   这是保守设计，不是缺陷，但会限制跨层剪枝。

6. **机器排序的适用性**：`sort(A)` 支配只在同构机器上成立；对
   unrelated machines 或带机器 release time 的实例，排序会丢信息，
   支配引理不成立。缓解：非同一机器时关闭 DOM。

7. **THRESH 收益有限**：40 个状态上只有 3/40 严格优于单点；在 20 个
   根间隙实例上没有闭合任何剩余间隙。它主要是一个“证书泛化/ anytime
   下界”工具，不是新的强下界。不要把它当作主卖点。

8. **THRESH 的单调性依赖固定窗口**：`caps` 必须与 `H` 无关；如果
   使用 `b=H` 或让窗口随 `H` 移动，`X_H` 的单调性可能被破坏。
   实现时必须固定 `(a,b)`，只让 `H` 变化。

9. **继承会传播错误**：如果某个局部下界实现有 bug，`F` 会把它带到
   整棵子树；这是比 v0.4 更危险的地方。缓解：checker 独立重算；
   默认只用 AGG/DFF/SUBSET 等可检查证据；对拍。

10. **证明 DAG 的工程复杂度**：`INHERIT`/`DOMINATED-BY`/`THRESH-CORE`
    的 checker 尚未实现；等状态环、DAG 共享、见证状态覆盖都需要
    仔细处理。一个错误的支配方向会接受假最优。

11. **实验规模小**：n=9–10、30 个实例、m=2；没有 PSPLIB；没有
    n≥20 的 anytime；不能外推到工业规模。时间数据是纯 Python 单次
    测量，不是 benchmark。

12. **泛化仍是结构性的**：本轮没有跨实例学习，也没有证明“在未见
    家族上更好”；v0.4 的 bandit 负结果仍然成立。CERT-REGION 只是
    可检查的缓存规则，不是统计泛化保证。

13. **最坏情况没有改善**：B&B 仍指数；A*/focal/支配/阈值都是常数或
    参数化改进。v0.5 的贡献是“一致搜索 + 更早的上界 + 更少的重复
    证明”，不是新的最坏情况界。

14. **Anytime 可能被支配剪枝伤害**：被支配状态上可能有一条更好的
    贪心调度；剪掉它之前若不算 `U_G`，会失去这个 incumbent。缓解：
    剪枝前跑一次贪心（§5.4）；或把被支配状态的 guide 作为 hint 传给
    支配者。

---

## 12. 一句话最大风险

**当前方案最大的风险是：A\* 一致性与支配剪枝的收益集中在“同一已调度集被多条动作路径到达、且贪心完成与 OPT 相关”的小型随机 DAG 上；在大型 precedence-heavy 实例上，focal 的多次贪心 rollout、支配表和周期阈值二分可能比它们省下的节点更贵，而 THRESH 对真正的优先约束间隙几乎无能为力。**
