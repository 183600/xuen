# 第 1 轮（新灵感循环第 1 轮；本轮灵感：「力觉传感」×「轨迹优化」）

> **基线**：上一循环产出 MetricVoiceGauge-NCD-HUTDH-v20（IP-420–424：PCA / CTS / CFC / HPC / CFCtrl）。v20 及更早的 v19（DCM/OGCC/CCV/DRS/OGC）、v17（CLP/S2C/HCG/PSV/APS/AMC）全部保留。
> 本轮纪律：**接触是可证书化的资源，轨迹是证书的连续化载体**。本轮只做一件事：**把“零碰撞”安全契约升级为“有界接触功”安全契约，并把该契约作为硬约束注入轨迹优化**；不推倒 v20，只在它上面增加一层“接触—时间”证书。

## 0. 直觉与动机

### 灵感 1（力觉传感 → 接触不是失败，而是需要被证书化的资源）

**直觉。** v20 的证书是二值的：SAFE / UNSAFE，本质是“零碰撞”。但人类操作从不追求零接触：拧瓶盖、推抽屉、擦桌子、插插头，接触本身就是任务的组成部分。力/触觉传感给出的不是“更灵敏的碰撞报警”，而是一条**连续的接触强度曲线**：法向力、切向摩擦、力矩、接触位置、滑移趋势。真正稀缺的不是“检测到接触”，而是“**证明这次接触在可容许范围内**”。

**严谨定义。** 对物体 o 定义**可容许扳手集**

W_adm(o) = { w = (f_n, f_t, τ) : 0 ≤ f_n ≤ f_max, ‖f_t‖ ≤ μ_s·f_n − δ_slip, ‖τ‖ ≤ τ_max }

其中 f_max 是物体/夹爪的承载上界，μ_s 是静摩擦系数下界，δ_slip 是滑移安全裕度，τ_max 是力矩上界；再叠加冲量与接触功上界

J(ξ) = ∫_0^T ‖f(t)‖ dt ≤ J_max,  E(ξ) = ∫_0^T ‖f(t)‖² dt ≤ E_max。

**力觉证书（Tactile Wrench Certificate, TWC）** 判定：沿轨迹 ξ 的整段接触都落在 W_adm(o) 内，且冲量/接触功不超限，且每个接触区间都被预先声明的接触调度覆盖。关键反直觉点：**力觉传感的价值不是让机器人“更早停止”，而是让轨迹优化“敢于规划接触”**——但前提是接触强度被证书包住，而不是靠运行时反馈临时救场。

### 灵感 2（轨迹优化 → 证书必须沿时间连续化，而不是点采样）

**直觉。** v20 的 CCV/HPC 是**点证书**：在参数 θ_k 上查询 SAFE。轨迹优化器一旦把点证书当作障碍约束，就会在样本之间“钻空子”：两个 SAFE 样本之间可以藏一段薄壁、一次瞬时过载或一次滑移。把采样加密只是把漏洞变窄，并没有消除漏洞；优化器恰恰会去搜索这些变窄的缝隙。

**严谨定义。** 设间隙函数 c(t) 为轨迹在 t 时刻到最近障碍的有符号距离。若轨迹速度满足 ‖q̇(t)‖ ≤ v_max，且 c 沿轨迹是 L_c-Lipschitz 的，则对任意区间 [a,b]，

c_lo(a,b) = min(c(a), c(b)) − ½·L_c·v_max·(b−a) ≤ min_{t∈[a,b]} c(t)。

**证书管（Certificate Tube, CT）** 用区间分支定界把点证书提升为整段轨迹上的连续证书：区间下界 ≥ ε_col 才标记 SAFE；否则继续细分，细到容差仍不满足就**整体拒绝**，绝不“跳过”。关键反直觉点：**安全性来自 Lipschitz 模数与区间下界，不来自采样密度**——加密采样只让证书更紧，不能让证书更真。

### 灵感 3（二者统一 → 证书约束轨迹优化，而非先优化后验证）

**直觉。** 传统流程是“先优化轨迹，再用碰撞检测拒绝”，把证书当事后过滤器，导致大量返工与过度保守；接触则更糟：一旦优化器规划了接触，事后只能靠力反馈硬扛。正确做法是让证书**进入优化问题的约束**。

**严谨定义。** **证书约束轨迹优化（Certificate-Constrained Trajectory Optimization, CCTO）** 在路点/时间步/接触调度上求解

min  T + w_e·E + w_f·∫‖f‖
s.t. c(q_k) − ½·L_c·v_max·Δt ≥ ε_col        （几何管）
     Δt ≤ Δt_max                              （反跨步）
     W_hat(q_k, σ_k) ⊕ E_w ⊕ E_rate·Δt ⊆ W_adm（力觉管）
     supp(σ) ⊆ ContactSchedule_certified      （无未证书接触）
     动力学 / 关节 / 力矩限位

几何约束是线性/二阶锥，摩擦锥是二阶锥，接触时序是混合整数；因此主体是可解的 SOCP/MISOCP。关键反直觉点：**优化器是证书的对手，不是朋友**——它会主动寻找证书最松的地方；所以证书必须以“最坏情况管”进入优化，而不是以“标称估计”进入。

### 三者如何统一

统一为 **v20 证书体系之上的“接触—时间”层**：v20 回答“θ 是否零碰撞”，v21 回答“整条轨迹 ξ 是否零碰撞，或接触扳手是否被证书包住”。TWC 是接触侧（扳手可容许性），LTL 是时间侧（点证书→连续管），CCTO 是决策侧（管约束下的轨迹优化），FGRG 是运行时侧（力反馈只能收缩管），CMCA 是代数侧（碰撞模式与接触模式的组合）。共享状态

ζ_ct = (contact_schedule, wrench_tube, cert_tube, delay_margin, mode_contact)。

## 1. 研究问题（轮次升级版）

- **Q1（力觉证书在不确定度下的可靠性）**：力/力矩传感器存在零漂、温漂、标定误差与延迟；如何把测量值膨胀成**保守区间**，使“测量上看似合规”的接触不会在真实扳手上越界？摩擦锥的滑移裕度如何随物体材质与磨损自适应而不牺牲可靠性？

- **Q2（点证书到连续管的提升）**：如何在只给定 SDF/CCV 点查询与轨迹运动学上界时，构造**可证明的**连续时间证书？区间分支定界的终止性、保守性与在线预算（50Hz 控制、10–30Hz 感知）如何权衡？薄壁、尖角、非凸物体下如何避免“跨步漏检”？

- **Q3（证书约束优化的可解性与保守性）**：把几何管、力觉管、接触时序同时写进优化后，问题是否仍是可处理的 SOCP/MISOCP？接触隐式（complementarity）变量如何被证书门控，避免优化器发明“免费接触”？优化器相对真实可行域的保守性间隙能否随采样与标定精度收紧？

- **Q4（运行时力反馈与证书的单调协调）**：控制频率高于力觉采样，且存在延迟；运行时力反馈如何**只收缩、不扩张**已提交的证书管？当实测力逼近上界、发生未建模冲击、或传感器掉线时，如何回退到 v20 的零碰撞路径？

## 2. 设计原则（在 P31–P33 基础上新增 P34–P37）

**P34 接触有界律（Bounded-Contact Law）**
任何被执行的接触都必须满足：其预测扳手管（含测量误差、模型误差与变化率外推）完整落在 W_adm(o) 内，且冲量 J ≤ J_max、接触功 E ≤ E_max、每个接触区间被接触调度覆盖。**未证书接触的集合为空**：CMCA 对未被 TWC 覆盖的接触区间一律返回 REJECT，优化器与运行时都无权“临时补证”。

**P35 证书管连续律（Certificate-Tube Continuity）**
点证书必须经 Lipschitz 区间提升为整段时间证书；区间下界 c_lo ≥ ε_col 才可标记 SAFE。**分支定界只允许两种叶子：已证明安全，或保守拒绝**；禁止“采样够密所以安全”的启发式。安全性的正确性锚是区间下界，而不是样本数量。

**P36 优化不可扩张律（Optimizer Non-Expansion）**
CCTO 只能在证书管内部选择轨迹与接触调度，不能修改证书、不能扩张 W_adm、不能放宽 ε_col 或 Δt_max。优化器输出的任何解都必须再通过一次**独立的** LTL + TWC 验证（commit 检查）；验证失败即丢弃，绝不降级为“信任优化器”。

**P37 力反馈收缩律（Force-Feedback Contraction）**
运行时力反馈只允许收缩已提交的管：降低速度、增大间隙裕度、缩短接触窗口、或直接中止接触。延迟 τ_d 通过 pad = F_rate·τ_d 外推与 v_safe = v_max − a_max·τ_d 降速补偿；**不存在任何由反馈触发的扩张算子**。传感器失效时接触模式立即禁用，回退 v20。

## 3. 与基线的接口（如何退化）

- TWC 失效（力/触觉传感器故障、标定过期、掉线）⇒ 接触模式禁用 ⇒ 只保留 v20 的零碰撞证书 ⇒ `Exec_v21^free ⊆ Exec_v20`；
- LTL 失效（Lipschitz 常数不可信、区间预算耗尽）⇒ 退回 v20 的密集点采样 + 更保守 margin ⇒ 仍是 v20 的子集；
- CCTO 失效（求解超时、MISOCP 不可行）⇒ 直接使用 v20 的采样计划或上一轮已证书轨迹 ⇒ 等价 v20；
- FGRG 失效（力觉延迟超界、冲击检测触发）⇒ 中止接触、执行 v20 认证退路 ⇒ 等价 v20；
- CMCA 失效（模式组合不可判定）⇒ 默认 FREE 模式（更保守）⇒ 等价 v20；
- **安全继承（需精确表述）**：v21 **不再声称** `Exec_v21 ⊆ Exec_v20`，因为接触模式是**安全契约的语义扩展**。v21 声称的是**契约分解**：
  `Exec_v21 = Exec_v21^free ∪ Exec_v21^contact`，其中 `Exec_v21^free ⊆ Exec_v20`，而 `Exec_v21^contact ⊆ ContactCertified(W_adm, σ)`。自由部分继承 v20；接触部分由 W_adm 重新定义“安全”。

## 4. 预期贡献

1. **力觉证书**：首次把“接触”从二值碰撞事件改写为**带不确定度与变化率外推的扳手管**，给出摩擦锥、冲量、接触功的统一可容许集与可机械验证的证书；
2. **证书管连续化**：用 SDF 的 Lipschitz 性质与区间分支定界，把 v20 的点证书提升为**可证明的整段轨迹证书**，从原理上消除“样本间漏检”，并证明安全性不依赖采样密度；
3. **证书约束轨迹优化**：把几何管、力觉管、接触时序写成 SOCP/MISOCP 约束，使“先优化后验证”变为“优化即受证书约束”，并给出独立 commit 验证与保守性间隙分析；
4. **单调运行时协调**：给出只收缩的力反馈治理器与延迟补偿，使接触在 50Hz 控制与 10–30Hz 力觉之间仍保有可验证边界；
5. **接触模式代数**：把零碰撞模式与有界接触模式组合成显式的安全契约代数，明确 v21 的安全语义扩展与回退路径，避免“接触模式悄悄扩大执行域”的隐性风险。

## 5. 本轮最大风险

**一句话**：v21 把安全契约从“零碰撞”扩展为“有界接触功”，其正确性完全押在**接触模型与力变化率上界**上；一次未建模的冲击（rate bound 被突破、接触刚度突变、物体突然卡死）就能让“已证书化的接触”变成真实过载，而 TWC/LTL/CCTO 全部形式通过——这是“证书化接触”的契约漏洞。

# IP-425 Tactile Wrench Certificate
@dataclass
class WrenchInterval:
    f_n: tuple[float, float]      # (lo, hi) 法向力
    f_t: tuple[float, float]      # (lo, hi) 切向力模长
    tau: tuple[float, float]      # (lo, hi) 力矩模长
    t: float


class TactileWrenchCertificate:
    def __init__(self, f_max, tau_max, mu_s, slip_margin,
                 J_max, E_max, rate_hi, dt_sample):
        self.f_max = f_max
        self.tau_max = tau_max
        self.mu_s = mu_s
        self.slip_margin = slip_margin
        self.J_max = J_max
        self.E_max = E_max
        self.rate_hi = rate_hi        # |dw/dt| 上界
        self.dt_sample = dt_sample    # 力觉采样间隔

    def admissible(self, wi: WrenchInterval) -> bool:
        # W_adm 是闭凸集（盒 ∩ 二阶锥 ∩ 球），只需检查区间最坏端点
        if wi.f_n[0] < 0.0 or wi.f_n[1] > self.f_max:
            return False
        # 最坏切向取切向上界、法向下界
        if wi.f_t[1] > self.mu_s * wi.f_n[0] - self.slip_margin:
            return False
        if wi.tau[1] > self.tau_max:
            return False
        return True

    def inflate(self, w_hat, e_w):
        # 测量误差 + 采样间隔内的力变化上界
        pad = e_w + self.rate_hi * self.dt_sample
        return WrenchInterval(
            f_n=(max(0.0, w_hat.f_n - pad), w_hat.f_n + pad),
            f_t=(max(0.0, w_hat.f_t - pad), w_hat.f_t + pad),
            tau=(max(0.0, w_hat.tau - pad), w_hat.tau + pad),
            t=w_hat.t)

    def certify(self, schedule, samples, errors):
        intervals = []
        for (t, w_hat), e_w in zip(samples, errors):
            wi = self.inflate(w_hat, e_w)
            if not self.admissible(wi):
                return WrenchCert.reject(t, "WRENCH_OUT_OF_ADM")
            intervals.append(wi)

        # 冲量与接触功用区间积分上界独立校验
        J_hi = integrate_upper([wi.f_n[1] for wi in intervals], self.dt_sample)
        E_hi = integrate_upper([wi.f_n[1] ** 2 for wi in intervals], self.dt_sample)
        if J_hi > self.J_max or E_hi > self.E_max:
            return WrenchCert.reject(None, "IMPULSE_OR_ENERGY_EXCEEDED")

        # 无未证书接触：每个接触区间必须被调度覆盖
        if not covers(schedule, intervals):
            return WrenchCert.reject(None, "UNSCHEDULED_CONTACT")

        return WrenchCert.ok(intervals, J_hi, E_hi, schedule)


# IP-426 Lipschitz Tube Lifter
class LipschitzTubeLifter:
    def __init__(self, L_clear, v_max, a_max, eps_col, dt_tol):
        self.L_clear = L_clear
        self.v_max = v_max
        self.a_max = a_max
        self.eps_col = eps_col
        self.dt_tol = dt_tol

    def lift_clearance(self, traj, clearance_fn):
        leaves, stack = [], [(0.0, traj.T)]
        while stack:
            a, b = stack.pop()
            ca, cb = clearance_fn(traj.q(a)), clearance_fn(traj.q(b))
            v_seg = min(self.v_max,
                        max_speed_on(traj, a, b) + self.a_max * (b - a))
            # 引理 157 的区间下界（比 min - L v (b-a) 更紧）
            c_lo = min(ca, cb) - 0.5 * self.L_clear * v_seg * (b - a)
            if c_lo >= self.eps_col:
                leaves.append(TubeLeaf(a, b, c_lo, "SAFE"))
            elif (b - a) <= self.dt_tol:
                # 保守拒绝：绝不把未证明的叶子当作 SAFE
                return TubeCert.reject(a, b, c_lo)
            else:
                m = 0.5 * (a + b)
                stack.append((a, m))
                stack.append((m, b))
        return TubeCert.ok(leaves)

    def lift_wrench(self, traj, schedule, twc, predicted_samples, errors):
        # 力觉管：逐段用 F_rate 与采样间隔膨胀；调用 TWC 校验
        padded = [(t, w_hat, e_w + twc.rate_hi * twc.dt_sample)
                  for (t, w_hat), e_w in zip(predicted_samples, errors)]
        return twc.certify(schedule, [(t, w) for t, w, _ in padded],
                           [e for _, _, e in padded])


# IP-427 Certificate-Constrained Trajectory Optimizer
class CertificateConstrainedTrajectoryOptimizer:
    def __init__(self, ltl, twc, dyn_bounds, dt_max):
        self.ltl = ltl
        self.twc = twc
        self.dyn = dyn_bounds
        self.dt_max = dt_max

    def solve(self, task, hpc, mode):
        # 变量：路点 q_0..q_K、时间步 dt、接触调度 sigma
        # 约束：
        #  (C1) 几何管: c(q_k) - 0.5*L_c*v_max*dt >= eps_col
        #  (C2) 反跨步: dt <= dt_max
        #  (C3) 力觉管: inflate(W_hat(q_k, sigma)) ⊆ W_adm
        #  (C4) 接触调度: supp(sigma) ⊆ 已证书接触窗口
        #  (C5) 动力学 / 关节 / 力矩限位
        # 目标: T + w_e*E + w_f*∫||f||
        prob = build_socp(task, constraints=[C1, C2, C3, C5])
        sol = solve_socp(prob)
        if mode in ("CONTACT", "HYBRID"):
            sol = refine_misocp(sol, contact_schedule=sol.sigma)
        return sol

    def commit(self, sol, hpc):
        # P36：优化器输出必须再过一次独立验证
        if not self.ltl.lift_clearance(sol.traj, hpc.clearance).ok:
            return None
        if not self.twc.certify(sol.sigma, sol.wrench_samples,
                                sol.wrench_errors).ok:
            return None
        return sol


# IP-428 Force-Gated Runtime Governor
class ForceGatedRuntimeGovernor:
    def __init__(self, twc, delay, rate_hi, a_max):
        self.twc = twc
        self.delay = delay
        self.rate_hi = rate_hi
        self.a_max = a_max

    def step(self, committed_tube, w_meas, e_w):
        # 延迟补偿：测量值 + 变化率上界外推
        pad = self.rate_hi * self.delay
        wi = WrenchInterval(
            f_n=(max(0.0, w_meas.f_n - e_w - pad), w_meas.f_n + e_w + pad),
            f_t=(max(0.0, w_meas.f_t - e_w - pad), w_meas.f_t + e_w + pad),
            tau=(max(0.0, w_meas.tau - e_w - pad), w_meas.tau + e_w + pad),
            t=w_meas.t)
        # P37：只收缩，不扩张
        if not self.twc.admissible(wi):
            return committed_tube.shrink_speed(
                factor=self.shrink_factor(wi), reason="FORCE_LIMIT")
        return committed_tube

    def shrink_factor(self, wi):
        excess = max(0.0, wi.f_n[1] - self.twc.f_max)
        return max(0.1, 1.0 - excess / max(1e-9, self.twc.f_max))


# IP-429 Contact-Mode Certificate Algebra
class ContactModeCertificateAlgebra:
    def compose(self, free_tube, wrench_cert, schedule):
        if wrench_cert.ok and covers(schedule, wrench_cert.intervals):
            return ContactMode(mode="CONTACT", cert=wrench_cert)
        if free_tube.ok:
            return ContactMode(mode="FREE", cert=free_tube)
        return ContactMode(mode="REJECT")

    def exec_set(self, plans):
        # 契约分解：自由部分继承 v20；接触部分由 W_adm 定义
        return [p for p in plans
                if (p.mode == "FREE" and p.free_cert.ok)
                or (p.mode == "CONTACT" and p.wrench_cert.ok)]

    def gate_contact_implicit(self, complementarity_set, schedule):
        # 接触隐式优化只允许被证书覆盖的接触模式进入可行域
        return [c for c in complementarity_set
                if covered_by(c, schedule)]

## 2. 推导

**引理 157（证书管的区间可靠性）**
设间隙函数满足 |c(t) − c(t′)| ≤ L_c·∫_{t′}^{t}‖q̇(s)‖ds ≤ L_c·v_max·|t − t′|。对区间 [a,b] 定义
`c_lo(a,b) = min(c(a), c(b)) − ½·L_c·v_max·(b−a)`。
则 `c_lo(a,b) ≤ min_{t∈[a,b]} c(t)`。
证明：对任意 t∈[a,b]，有 c(t) ≥ c(a) − L_c·v_max·(t−a) 与 c(t) ≥ c(b) − L_c·v_max·(b−t)。两式取最大得
c(t) ≥ min(c(a),c(b)) − L_c·v_max·min(t−a, b−t) ≥ min(c(a),c(b)) − ½·L_c·v_max·(b−a)。
故 c_lo 是真实下界；若 c_lo ≥ ε_col，则整段区间无碰撞。∎

**引理 158（反跨步完备性）**
LTL 的分支定界只在 `c_lo ≥ ε_col` 时标记 SAFE；`c_lo < ε_col` 的叶子要么继续二分，要么在宽度 ≤ dt_tol 时整体拒绝。由于 c_lo 是真实下界（引理 157），任何被标记 SAFE 的叶子确实安全；任何薄壁、尖角或瞬时危险只会导致细分或拒绝，**不可能被跨过**。故安全性不依赖采样密度，而依赖区间下界；薄壁不会被“漏检”，最坏后果是保守拒绝。∎

**引理 159（扳手证书在凸性与不确定度下的可靠性）**
W_adm = {f_n∈[0,f_max]} ∩ {‖f_t‖ ≤ μ_s·f_n − δ_slip} ∩ {‖τ‖ ≤ τ_max} 是盒、二阶锥与球之交，故为闭凸集。若每个采样点的膨胀区间 `[w̃ − e_w − F_rate·Δt, w̃ + e_w + F_rate·Δt]` 的所有顶点（区间端点组合）落在 W_adm，则由凸性（凸集对端点凸组合封闭）与 `‖w(t) − w(t_k)‖ ≤ F_rate·Δt` 可知整段真实扳手落在 W_adm。冲量与接触功另用区间积分上界独立校验。∎

**引理 160（力反馈单调收缩）**
FGRG 的每次 `step` 只返回原管或 `shrink_speed` 后的管，代码中不存在任何扩张算子；延迟 τ_d 通过 `pad = F_rate·τ_d` 外推，并以 `v_safe = v_max − a_max·τ_d` 降速补偿。因此只要真实扳手满足变化率上界，延迟窗口内的真实扳手仍在膨胀区间内，反馈不会把已越界接触认证为安全。∎

**引理 161（v21 安全契约分解）**
定义 `Exec_v21 = Exec_v21^free ∪ Exec_v21^contact`。则
(i) `Exec_v21^free ⊆ Exec_v20`：FREE 模式仍使用 v20 的 CCV/HPC 间隙，只是经 LTL 连续化并加保守管；
(ii) `Exec_v21^contact ⊆ ContactCertified(W_adm, σ)`：CONTACT 模式必须被 TWC 覆盖。
因此 v21 不声称整体子集关系，而声称**契约分解**：自由部分继承 v20，接触部分由 W_adm 重新定义“安全”。这正是 v21 的语义扩展，也是其最大风险来源。∎

**引理 162（无未证书接触）**
CCTO 的任何接触调度 σ 在 `commit` 前必须通过 `TWC.certify`；CMCA 在组合时再次要求 `covers(σ, intervals)`；接触隐式变量还须经 `gate_contact_implicit`。若 σ 含未被证书覆盖的接触区间，则 commit 或 CMCA 返回 REJECT。故不存在“优化器自行发明、未经力觉证书确认”的接触。∎

**引理 163（CCTO 的保守性间隙）**
CCTO 相对真实可行域在每个长度为 Δt 的区间上最多多损失 `½·L_c·v_max·Δt` 的几何裕度与 `2(e_w + F_rate·Δt)` 的力觉裕度。当 Δt→0 且 e_w→0 时，该间隙趋于 0；但收紧只提高活性，不改变可靠性（引理 157–159）。故保守性是可调的，可靠性不是。∎

**引理 164（LTL 终止性）**
分支定界每轮把区间宽度减半；当宽度 ≤ dt_tol 时叶子必然终止（要么 SAFE，要么拒绝）。故叶子数至多 O(T/dt_tol)，算法在有限步内终止；最坏情况是整段拒绝，而不是无限细分或错误接受。∎

## 6. 已知风险与失效模式

1. **接触模型误差**：预测扳手 W_hat 依赖刚度/阻尼/摩擦模型；物体卡死、软硬突变或表面附着会让真实力远超预测。缓解：在线辨识、冲击检测、保守 rate 上界、力超限即中止。

2. **力变化率上界被突破**：F_rate 是延迟补偿与外推的核心假设；一次硬碰撞可在毫秒级产生尖峰，超过 rate 上界。缓解：硬件低通/机械柔顺、冲击前减速、独立的高频触觉触发。

3. **标定漂移与温漂**：力/力矩传感器零漂随温度与负载变化，e_w 低估会导致“形式合规、实际过载”。缓解：定期零漂校准、温度补偿、双传感器交叉校验。

4. **摩擦锥边界的过度乐观**：优化器会贴着摩擦锥边界规划，长期磨损、油污或振动会让 μ_s 下降，导致滑移。缓解：滑移裕度 δ_slip、在线摩擦估计、触觉滑移检测。

5. **区间分支定界爆炸**：高维构型或长轨迹下叶子数增长，在线预算可能不足。缓解：增量/warm-start、GPU 并行、分层降级为保守拒绝。

6. **安全契约语义漂移**：v21 的接触模式使 `Exec_v21 ⊄ Exec_v20`；若把“有界接触”误读为“仍然零碰撞”，会在审计与责任界定上产生漏洞。缓解：显式契约分解、模式标记、审计日志、默认 FREE。

7. **多接触耦合**：同时多点接触时 W_adm 的逐点笛卡尔积会忽略力分配耦合，可能整体可行而局部过载。缓解：联合扳手多面体、接触力分配约束、分布式触觉。

8. **与 v20 时间尺度不一致**：深度相机 10–30Hz、力觉 100–1000Hz、控制 50Hz，证书管的采样与 TTL 需分层管理，否则出现“证书过期但仍在执行”。缓解：分层 TTL、APS 新鲜度阶梯、过期即回退。

## 7. 本轮最大风险

**一句话**：v21 把安全契约从“零碰撞”扩展为“有界接触功”，其正确性完全押在接触模型与力变化率上界上；一次未建模的冲击（rate bound 被突破、接触刚度突变、物体突然卡死）就能让“已证书化的接触”变成真实过载，而 TWC/LTL/CCTO 全部形式通过——这是“证书化接触”的契约漏洞。
