# 第 13 轮（新灵感循环第 1 轮）· SCOPE：把动作放进物体规范系，把 94 个得分点变成阶段变量

> 检索/复核日期：**2026-10-31（UTC）**。承接第 12 轮 CHUNK-SERVO：不推倒「30 步规划 + 5 步视觉伺服」，而是把它降为末端执行层；本轮把创新前移到**动作表示**与**评测信号**。三个灵感词是「评测指标」「动作空间」「跨物体泛化」。

## 0. 先给结论：公开榜首 29.7% 是预览数据；真正的瓶颈是「动作没有物体参照、模型没有阶段状态」

本轮先把一个会误导整条研究路线的事实钉死：**公开榜单不是真实评测结果，而是 `gen_leaderboard.py` 生成的预览。**

- 8 个模型 × 32 个任务 = **256** 条任务记录；若每任务 10 次，任务成功率必须是 10% 的整数倍，但 **255/256** 不是（例如 27.29%、27.85%、37.01%）。
- 对每个模型做 `step_score ~ success_rate` 回归：**R² > 0.999999，最大残差 < 0.006**，斜率 1.305–1.371；这不是实测步骤分，是脚本生成的线性缩放。
- `runs.html` 只有 256 条（8×32），不是 8×32×10；`details.html` 的 32 个任务视频全是“测试视频占位，后续可替换为真实视频文件”。

所以：**29.7% 不是真实 SOTA，不能用来反推任务难度，也不能用来证明“所有模型都卡在 30%”。** 真实基线必须在单任务不计分通道上自己测。

但公开榜单背后有一个真实事实：官方评分不是单一成功率，而是 **32 任务 × 100 分、共 94 个得分点**；每任务 2–5 步，步骤权重 20–50；排名先看 32 任务总平均成功率，再相同看总平均步骤分。**步骤分是真实存在的稠密信号，只是公开榜单把它伪造成了 success 的线性函数。**

我的判断是，真正的共享瓶颈有三个，而且互相耦合：

1. **参照系缺口**：WLA/主流 VLA 的动作以 base 系或当前 EE 系为参照；物体一换、位置一动，绝对轨迹就变。官方未见物品 trial 往往直接“缺少标准物体”，不是只换颜色。
2. **阶段缺口**：模型输出 30 步开环 chunk，没有“现在完成到第几个得分点”的内部状态；跨阶段边界不能重规划，人为干扰后不能判断该重试哪一步。
3. **度量缺口**：公开榜单的 step score 是合成的；团队若只盯 success，就看不到“前 50 分拿到了、最后 40 分丢了”这种真实失败结构。

所以本轮押注 **SCOPE**（Subgoal-Canonical Object-frame Policy Execution）：

> **用同一张 WLA 权重，把动作从 base 系绝对轨迹改写成「受器/目标规范系」下的绝对轨迹，并把官方 94 个得分点变成模型内部的阶段变量；跨物体泛化靠规范系，长程成功靠阶段对齐，CHUNK-SERVO 只保留为末端 5 步闭环。**

三个可验证创新点，不是三个宏大名目：

1. **SCOPE-Frame**：离线从 33k 成功演示发现「任务规范系」，在线用头双目 + 腕部内参估计/跟踪；把 canonical state 和 canonical absolute action 送进同一张 WLA；失败回退 base 系。
2. **SCOPE-Progress**：把 94 个得分点变成阶段头（phase head + completion head），在每个 5 步 chunk 边界判断“完成到哪一步、是否卡住、是否重试”；它是同一 checkpoint 的辅助输出，不是第二个策略。
3. **SCOPE-Matrix**：5 类泛化 × 32 任务的矩阵化评测；公开榜单只看 success，我们看 per-axis success + step score + 失败阶段；用矩阵决定数据与算力投放。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **评测指标** | 94 个得分点 → 阶段头 + 5×32 矩阵 + 单任务通道配对 A/B | 不优化公开榜单的合成 step score；不把 29.7% 当真 |
| **动作空间** | canonical state + canonical absolute EE action；base 系回退；EE/joint 消融 | 不把“相对动作换个坐标系”冒充创新；不训 32 个专家 |
| **跨物体泛化** | 受器/目标规范系 + 轨迹对齐 + 物体替换增强 + 72 个相关 Dex1 repo | 不靠颜色阈值硬编码；不假设未见物品只是换色 |

## 2. 诊断：三个缺口，不是三个独立问题

### 2.1 参照系缺口

WLA 的原生动作是相对当前 EE 的 SE(3)：`T_rel = T_Ecurr^{-1} T_Efuture`。这个量对“在哪个 base 系下表达”是不变的；**简单地把当前和未来都换到规范系，相对动作完全不变**。所以“换坐标系”本身不是创新。

真正要做的是改变**状态和目标**：

- canonical state：`s_F = T_BF^{-1} T_BE`
- canonical absolute action：`a_F = T_BF^{-1} T_BE_future`
- 回映射：`a_B = T_BF a_F`

这样模型学的是“EE 相对受器应该在哪”，而不是“EE 相对 base 应该在哪”。物体换位置/换外观时，前者更稳定；后者要靠模型从图像里重新记住绝对坐标。

### 2.2 阶段缺口

官方 94 个得分点给出了天然的阶段结构，但模型没有这个变量。固定 5 步 chunk 只能保证“每 167ms 看一次”，不能保证“知道现在该做第几步”。在 4–5 步任务里，早期阶段失败会丢后续所有分；在人为干扰 trial 里，物体被移动后，模型可能继续执行旧阶段的 chunk。

阶段头要回答三个问题：

1. 当前处于第几个得分点（phase index）；
2. 当前得分点完成了没有（completion probability）；
3. 最近 N 个 chunk 有没有进展（stall / perturbation）。

它不是第二个策略；它是同一 checkpoint 的辅助输出 + 确定性 scheduler。

### 2.3 度量缺口

公开榜单把 step score 伪造成 success 的线性函数，导致：

- 看不到“早期步骤成功、最后一步失败”的真实结构；
- 无法判断一个模型是“抓不到”还是“放不准”；
- 无法用 step score 做模型选择（它和 success 共线）。

官方步骤分是 100 分/任务、94 个得分点；我们应该自己从 rubric 构造阶段标签，用单任务通道验证，而不是优化公开预览的合成值。

### 2.4 任务结构

- 2 步（11）：T01、T02、T03、T05、T08、T14、T19、T23、T24、T30、T32。
- 3 步（14）：T04、T06、T07、T10、T11、T12、T13、T20、T21、T25、T26、T27、T29、T31。
- 4 步（5）：T09、T15、T18、T22、T28。
- 5 步（2）：T16、T17。

- 形变：T16、T18、T19、T23、T31。

这不是一个“最后 3 厘米”的问题；是**物体参照 + 阶段状态 + 接触/形变/精密**的组合问题。

## 3. 方法：SCOPE

### 3.1 总架构

```
挑战赛 obs
  ├─ adapter: RGB→BGR, rpy→rot6d, language→instruction, 图像 resize 336×448
  ├─ SCOPE-Frame: 头双目深度 + 腕部内参 → 受器/目标规范系 T_BF
  ├─ canonical state: s_F = T_BF^{-1} T_BE
  ├─ WLA / SCOPE (同一 checkpoint)
  │    ├─ action head: canonical absolute EE chunk a_F (30 步规划)
  │    └─ progress head: phase index + completion logits
  ├─ map back: a_B = T_BF a_F
  ├─ clip / fallback / token
  └─ 返回挑战赛 action chunk (T=5 或 8)
```

一段话：**WLA 继续做 30 步规划；SCOPE 把它的状态和动作目标换成规范系，并让它在每个 5 步边界报告“做到第几步”；CHUNK-SERVO 的视觉伺服仍是末端接触的最后一层。**

### 3.2 为什么是 canonical absolute action，而不是 canonical relative action

- 相对动作 `T_Ecurr^{-1} T_Efuture` 对公共左乘 frame 不变；换 F 不改变相对目标。
- 绝对动作 `T_BE_future` 换到 F 后是 `T_FE_future`，它**依赖 F**；模型必须使用规范系，目标也随物体位置变化而保持相对一致。
- 所以主方法是 canonical absolute action；canonical relative action 只作为消融 A1（只改状态不改目标）。A1 更稳、对 frame 误差不敏感，但可能收益较小；A2 更强、但 frame 误差会被放大。G1/G4 先比较 A1 vs A2，A2 在 frame 噪声下崩就退回 A1 + CHUNK-SERVO。

### 3.3 规范系怎么来

**离线：轨迹对齐发现规范系（不依赖人工物体标注）**

对每个任务/子阶段：

1. 取所有成功演示的绝对 EE 轨迹 `T_BE(t)`；
2. 用视觉/受器初始化 `F_e`；
3. 在 F 下计算 canonical 轨迹 `T_FE(t) = F_e^{-1} T_BE(t)`；
4. 选一条 medoid 参考轨迹，DTW 对齐；
5. 对每条 episode 用 Procrustes/ICP 优化 `F_e`，最小化它与参考的 canonical 轨迹差异；
6. 迭代到收敛，得到任务规范系模板 + 参考轨迹。

这个算法的好处：

- 不需要物体 6D 标注；
- 对对称物体（杯子、碗、盘子）可以用轨迹消歧 yaw；
- 可以把视觉估计的 frame 误差吸收到离线模板里；
- 每个子阶段可以有自己的 F（例如“抓取阶段以物体为 F”“放置阶段以受器为 F”）。

**在线：视觉估计 + 跟踪 + 回退**

- 头双目 rectified → SGBM/轻量立体匹配 → 点云；
- RANSAC 桌面平面 → 去掉桌面；
- 受器/目标分割：颜色/几何/凹性/边缘，或同一 checkpoint 的 VLM grounding 头（不引入第二个学习模型）；
- PCA/ICP 估计 `T_BF`；时序跟踪（上一帧 + 点云配准）；
- 置信度：内点率、重投影误差、时序一致性；
- 置信度低 → 用上一帧；持续低 → 回退 base 系（`F=B`）。

**训练时做 frame randomization**：随机扰动 F，或随机构造 F（受器/桌面/物体），让模型见过“规范系不准”和“回退 base”的情况，避免测试时一错全错。

### 3.4 阶段头与调度

**标签**

- 官方 `score_steps` 给出每任务 2–5 个有序阶段；
- 用夹爪开合事件 + EE 运动阶段（approach / grasp / lift / transport / place / release）做初始分割；
- 对多物体任务（3 个水果/盘子/试管），每个 grasp-place 循环对应一个阶段；
- 对无夹爪事件的任务（开盖、拉拉链、倒药），用视觉变化 + 人工标注 20 条/任务做种子；
- 训练一个小型 temporal head（VLM pooled feature + state + frame pose → phase logits + completion logits）；
- 用高置信预测伪标注其余数据；人工只抽检。

**调度**

- `action_chunk_size` 固定为 5（或 8）；WLA 内部规划 30 步，只返回前 5 步；
- 每个 chunk 边界：
  - completion 高且稳定 K 帧 → 阶段前进，重规划；
  - completion 长期低 + frame jump / 物体移动 → 判定扰动，重定位/重规划；
  - 连续 N 个 chunk 无进展 → 重试当前阶段（回到安全预抓取位）；
- 阶段头只做“是否前进/重试”的门控，不直接生成动作；动作仍由同一 WLA 生成。

### 3.5 与 CHUNK-SERVO 的关系

| 第 12 轮 | 本轮处理 |
|---|---|
| 30 步规划 + 5 步视觉伺服 | **保留**，作为末端执行层 |
| DG-KEYFRAME 演示检索 | **保留**，作为规范系模板/目标库 |
| 数字孪生标定外参/增益/RTT | **保留但缩权**：只做相机/延迟/安全边界，不做大模型训练 |
| C1/C2/C3 合规 | **保留** |
| 任务组合/单任务通道 | **保留**，用 94 得分点矩阵升级 |
| “腕部无内参” | **剪掉**：数据集有内参 |

一句话：**CHUNK-SERVO 是手，SCOPE 是眼睛和动作语言；手不换，眼睛和语言换。**

## 4. 评测与竞赛策略

### 4.1 官方指标

- 任务成功率 `p_t`（10 次）；总平均 `P = (1/32) Σ p_t`。
- 任务步骤分 `s_t`（0–100）；总平均 `S = (1/32) Σ s_t`。
- 排名：`P` 降序 → `S` 降序 → 提交更早。
- 10 次 trial 的 `p_t` 标准误：`sqrt(p(1-p)/10)`；p=0.3 时约 14.5pp。32 任务总平均的 SE 约 2.6pp（独立假设）。**小于 5pp 的改进不能只靠一次 10-trial 评测下结论。**
- 步骤分每任务 100 分，但单步权重 20–50，粒度高；平均到 32 任务后可做模型选择。

### 4.2 5×32 泛化矩阵

| 轴 | 官方 trial 数 | 我们要看 |
|---|---:|---|
| 位置 | 2/任务 | 初始位置偏移下的成功率/步骤分 |
| 干扰物 | 2/任务 | 额外物体下的抓取/放置精度 |
| 桌面背景 | 2/任务 | 颜色/纹理变化下的感知稳定性 |
| 未见物品 | 2/任务 | 同类不同外观/缺失标准物体 |
| 人为干扰 | 2/任务 | 抓取前/中/后移动物体/受器 |

官方每格只有 2 次，噪声很大；我们用单任务通道做 20–50 次/条件，官方 10 次只做最终确认。矩阵按 task 为单元做 paired bootstrap，不把 320 次当 320 个独立样本。

### 4.3 任务组合

- 先做 6 个代表任务的单任务探针：**T01**（未见物体+挂钩）、**T05**（双手+网线）、**T12**（接触+锁）、**T16**（形变+5 步）、**T26**（插入+精密）、**T30**（小物体+多钉）。
- 再扩到 32 任务矩阵；按 `q_t × Δ / cost` 分配工程，`q_t=1/32` 等权。
- 先交安全基线锁接口/合规，再做 SCOPE 的 A/B；不要等“完美模型”才提交。
- 公开榜单是预览，不作为任务难度表；任务难度用我们自己的 baseline + rubric 步数 + 接触/形变分类。

### 4.4 实验门 G0–G7

| 门 | 问题 | 通过标准 |
|---|---|---|
| G0 | 接口/动作适配 | 32 任务单步 shape/dtype/token 全过；RGB/BGR、rpy→rot6d、pivot/gripper clip 正确；reset 隔离；延迟可接受 |
| G1 | 规范系发现 | 离线 canonical 轨迹方差显著下降；在线 frame 误差/置信度可测；回退 base 不崩 |
| G2 | 阶段标签 | 抽检 phase F1 > 0.8；completion 校准误差可接受 |
| G3 | 离线动作 | canonical absolute action 的 MSE/DTW 优于 base absolute；回映射误差小 |
| G4 | 单任务 A/B | WLA baseline vs SCOPE-Frame vs +Progress；至少 3 个代表任务、20–50 trials，success 或 step score 有稳定提升 |
| G5 | 泛化矩阵 | 未见物品/人为干扰轴提升，位置/背景/干扰物不回归 |
| G6 | 全量提交 | 32 任务无接口失败；success/step 不低于 baseline；失败可分诊 |
| G7 | 消融 | frame vs base；absolute vs relative；per-task vs global norm；chunk 3/5/8/30；progress on/off；物体替换数据 on/off |

### 4.5 风险与合规

- **单模型**：SCOPE-Frame 用经典 CV（SGBM/RANSAC/PCA/ICP），不引入第二个学习模型；SCOPE-Progress 是同一 checkpoint 的辅助头；scheduler 是确定性代码。若用外部 SAM/Detector，必须并入同一 checkpoint 或放弃。
- **无深度/力/触觉**：深度来自头双目；接触靠视觉 + 本体感觉；透明/反光物体用腕部近景 + 多视角兜底。
- **规范系误差**：训练时 frame randomization + 回退 base；置信度低不硬用。
- **阶段头噪声**：先做诊断，不直接控制；G2 不过门就只保留可视化。
- **评测语义**：pivot/gripper/EE 控制器行为未知；单任务通道先做“零动作/保持动作/小步动作”探针。
- **算力/存储**：32 repo 约 811GB；72 repo 更大；先下代表任务 + 流式读取；24GB 单卡可微调 action head，但全量训练建议 1–2×A100 80GB。
- **公开榜单**：合成预览；不优化、不引用为 SOTA。

## 5. 一句话押注

> **把动作放进受器/目标规范系，把 94 个得分点放进模型内部的阶段变量；用同一张 WLA 权重完成「规范系动作 + 阶段进度 + 子目标对齐执行」，CHUNK-SERVO 只保留为末端 5 步闭环。**

# 第 13 轮产物 · SCOPE 技术报告

> 检索/复核日期：**2026-10-31（UTC）**。本报告承接第 12 轮 CHUNK-SERVO，但把主创新从「末端 5 步视觉伺服」前移到「动作表示 + 阶段评测」。SCOPE = **S**ubgoal-**C**anonical **O**bject-frame **P**olicy **E**xecution。

## 0. 结论与边界

### 0.1 一句话结论

> 用同一张 UnifoLM-WLA-1.0 权重，把状态和动作目标从 base 系绝对量改成「受器/目标规范系」下的绝对量，并把官方 94 个得分点变成同一 checkpoint 的阶段头；跨物体泛化靠规范系，长程成功靠阶段对齐，CHUNK-SERVO 只保留为末端 5 步闭环。

### 0.2 证据等级

- **A**：官方文档、官方 JSON、官方代码、数据集 `meta/info.json`/`meta/stats.json` 可直接核对。
- **B**：我们基于 A 级数据的回归/统计/工程推断，结论可复现但非官方声明。
- **C**：假设/先验，必须在单任务不计分通道或真机实测。

### 0.3 本轮不做什么

- 不把公开榜单的 29.7% 当真实 SOTA；不优化它合成的 step score。
- 不为每个任务训一个专家策略（违反单模型规则）。
- 不引入第二个学习策略；规范系估计用经典 CV，阶段头并入同一 checkpoint。
- 不假设腕部相机没有内参（数据集有）。
- 不假设“相对动作换个坐标系”就是创新（相对动作对公共左乘 frame 不变）。
- 不在没有单任务通道验证前，直接烧正式 32 任务提交。

**注**：`human` 列是为可读性做的摘要，不是逐字引用；完整原文见 `info.json` 的 `human_1_note`/`human_4_note`。

**读法**：

- 2 步任务先 grasp 再 place/contact，最后一步 50 分；3 步任务最后一步 40 分；4/5 步任务等权。
- 4/5 步任务一旦早期阶段失败，后续分全部丢失；阶段头的价值最高。
- 成功很可能要求完成全部得分点（C 级假设）；步骤分是部分完成，官方确实存在。
- 23/32 任务有 `unseen_object_3` 说明；30/32 有 human 说明；缺失说明需要视频/任务介绍补全。

### 1.3 泛化设置的直接含义（A）

- **未见物品不是“只换颜色”**：HangCup「缺少红色杯子和塑料架子」、FruitCollection「缺少不同果篮」、PackDoll「缺少绿色和紫色娃娃」、Unlock「缺少一把绿色锁」、PlugInEthernet「不同的网线跟端口」。这些是**标准物体被替换或拿掉**，模型必须靠类别/功能/几何，而不是记忆训练实例。
- **人为干扰是具体脚本**：HangCup「杯子向后 / 向右」、PlugInEthernet「把网线移开 / 把插口移开」、Unlock「锁向左 / 中途把锁拿走」、FoldTowel「将叠完的毛巾翻开」、PickOutBatteries「抓取前动底座 / 抓取后动绿色盒子」。这些发生在抓取前、抓取中、抓取后，要求**在线重定位 + 阶段判断**。
- **位置/干扰物/背景** 没有逐任务 notes；需要自己构造矩阵。

## 2. 问题形式化

### 2.1 评分与不确定性

任务 `t` 的成功率：

```
p_t = (1/10) Σ_{i=1}^{10} 1[task t trial i success]
P = (1/32) Σ_t p_t
S = (1/32) Σ_t s_t,  s_t ∈ [0,100]
rank = sort by (P desc, S desc, submit_date asc)
```

方差：

```
Var(p_t) = p_t(1-p_t)/10
SE(p_t) = sqrt(p_t(1-p_t)/10)     # p=0.3 -> 14.5pp
SE(P) ≈ sqrt(Σ_t Var(p_t))/32     # 独立假设，p=0.3 -> 2.6pp
```

**含义**：10 trials/task 只能分辨较大的任务级差异；小于 5pp 的总平均改进不能靠一次评测下结论。单任务通道要做 20–50 trials/条件，并用配对设计。

步骤分是 100 分/任务、94 个得分点；单步权重 20–50，粒度高。它是真实的稠密信号，但公开榜单把它伪造成 `k×success`；不要用公开值做模型选择。

### 2.2 动作与规范系

定义：

- `B`：机器人 base 系。
- `F`：任务规范系（受器/目标/桌面/物体初始位姿）。
- `T_BF = (R_BF, t_BF)`：F 在 B 中的位姿。
- `T_BE`：EE 在 B 中的绝对位姿。
- `T_FE = T_BF^{-1} T_BE`：EE 在 F 中的绝对位姿。
- 完整状态里，EE 两个 9D 槽换成 canonical EE；gripper/waist/lower_body 保持原义；`T_BF` 的 xyz+rot6d + 置信度作为额外 10D token 送进 state projector（输入从 120D 扩到 130D，只改 projector/action head，冻结 VLM）。

WLA 原生相对动作：

```
T_rel = T_Ecurr^{-1} T_Efuture
```

**引理（相对动作的 frame 不变性）**：

```
(T_BF^{-1} T_BEcurr)^{-1} (T_BF^{-1} T_BEfuture)
= T_BEcurr^{-1} T_BF T_BF^{-1} T_BEfuture
= T_BEcurr^{-1} T_BEfuture
= T_rel
```

所以“把相对动作换到 F”不改变目标；**只改状态不改目标**的收益有限。SCOPE 主方法是：

```
canonical state:   s_F = T_BF^{-1} T_BE
canonical action:  a_F = T_BF^{-1} T_BE_future   (absolute)
map back:          a_B = T_BF a_F
```

这样模型学的是“EE 相对受器应该在哪”，而不是“EE 相对 base 应该在哪”。目标随 F 变化；F 由物体/受器定义，所以跨物体/跨位置更稳定。

**但 A2 有一个真实代价**：canonical absolute action 对 `T_BF` 的旋转误差会按力臂放大（0.3m 力臂上 5° 误差约 2.6cm）。A1（只改状态、保留相对动作）对 frame 误差不敏感，但 action 目标不变，收益可能较小。因此 G1/G4 必须做 A1 vs A2；A2 在 frame 噪声下崩，就退回 A1 + CHUNK-SERVO，不要为了“规范系”三个字硬上。

**回退**：若 `F` 置信度低，令 `F=B`，退化为 base 系绝对动作；训练时做 frame randomization，让模型见过两种情况。

### 2.3 阶段与进度

官方 `score_steps` 给每个任务 `K_t` 个有序阶段（2–5）。定义：

- `z_t ∈ {0,...,K_t}`：当前已完成阶段数；`z=0` 未开始，`z=K_t` 全部完成。
- `c_t,k ∈ [0,1]`：第 k 个得分点完成概率。
- `progress = (z, c, stall, perturbation)`。

阶段头输出 `K_t+1` 个 phase logits 和 `K_t` 个 completion logits；调度器：

```
if c[z] > τ_done for K_done frames: z += 1; replan
if frame_jump > τ_frame or c[z] < τ_stall for N chunks: re-localize; maybe retry z
if z == K_t: continue until evaluator ends
```

阶段头不生成动作；动作仍由 WLA 生成。它是同一 checkpoint 的辅助输出。

### 2.4 5×32 泛化矩阵

轴 `a ∈ {position, distractor, background, unseen, human}`；任务 `t`；每格 2 次官方 trial。定义：

```
P_a = (1/32) Σ_t (1/2) Σ_{i=1}^2 1[success_{t,a,i}]
S_a = (1/32) Σ_t (1/2) Σ_i s_{t,a,i}
```

官方每格 2 次，噪声大；用单任务通道做更多 trial。统计以 task 为单元做 paired bootstrap；不把 320 次当独立样本。

## 3. 系统设计

### 3.1 架构

```
challenge obs
  │
  ├─ adapter
  │   ├─ RGB -> BGR
  │   ├─ EE [6] xyz+rpy -> [9] xyz+rot6d
  │   ├─ language -> instruction
  │   └─ image resize -> 336x448
  │
  ├─ SCOPE-Frame
  │   ├─ head stereo rectified -> depth (SGBM / light stereo)
  │   ├─ RANSAC table plane -> remove
  │   ├─ receptacle/target segmentation (classical or same-checkpoint head)
  │   ├─ PCA/ICP -> T_BF
  │   ├─ temporal tracking + confidence
  │   └─ fallback F = B
  │
  ├─ canonical state s_F = T_BF^{-1} T_BE
  │
  ├─ WLA / SCOPE (one checkpoint)
  │   ├─ action head -> a_F (30-step plan)
  │   └─ progress head -> phase/completion
  │
  ├─ map back a_B = T_BF a_F
  ├─ clip / NaN guard / last-safe fallback
  └─ challenge action chunk (T=5 or 8) + token
```

### 3.2 进程/端口/reset

- 评测跨 N 台机器人，提交从 8765 起暴露 N 个连续端口；每端口独立。
- 模型可以共享（同一 GPU 进程 + 请求队列），但**每端口必须有独立的 episode state**：frame、progress、history、last_safe_action、language、step index。
- `reset()` 清空该端口 state；不得影响其他端口；不得把上一 episode 的 frame/progress 带入下一 episode。
- 若 N 较大，单模型实例可能成为延迟瓶颈；用 batch/queue 或每 GPU 一个实例，按显存/延迟实测。
- `get_action` 必须线程安全；不要在请求间共享可变 numpy buffer。

| `action.pivot` [T,7] | 同名 [1,T,7] | 去 batch 维 |
| `meta.token` | — | 包装层加 |

**不要**把 `cam_right_high` 丢掉：它可用于双目深度/规范系估计；WLA 模型只用头左 + 两腕，但我们的 frame estimator 可以用头右。

### 3.4 `get_action` 伪代码

```python
class SCOPEPolicy:
    def reset(self):
        self.frame = None
        self.frame_conf = 0.0
        self.phase = 0
        self.hist = []
        self.last_safe = None
        self.step = 0
        return {"ok": True}

    def get_action(self, obs):
        self.step += 1
        obs_wla = adapt_obs(obs)                 # RGB->BGR, rpy->rot6d, language
        images = obs_wla["images"]

        # 1. frame estimation (chunk boundary; reuse previous if low confidence)
        frame = estimate_frame(obs, prev=self.frame)
        if frame.conf < TAU_FRAME:
            frame = self.frame if self.frame is not None else base_frame()
        self.frame = frame

        # 2. canonical state
        state_F = canonical_state(obs_wla["state"], frame)

        # 3. one model forward: canonical action plan + progress
        a_F, prog = self.model.predict(
            images=images,
            state_F=state_F,
            frame_pose=frame.pose,
            lang=obs_wla["instruction"],
            history=self.hist,
        )                                      # a_F: (30, 6+1+1+7); prog: phase/completion

        # 4. map back to base
        a_B = map_back(a_F, frame)             # (30, ...)
        a_B = clip_to_stats(a_B, task=obs.task)
        a_B = nan_guard(a_B, self.last_safe)

        # 5. progress at chunk boundary
        self.phase, replan, retry = update_progress(
            prog, self.phase, frame, self.hist
        )
        if replan or retry:
            self.model.reset_plan()            # next call re-plans
        self.last_safe = a_B[0].copy()

        # 6. return fixed-size chunk
        T = self.action_chunk_size             # 5 or 8
        return format_action(a_B[:T], self.token)
```

**说明**：

- `action_chunk_size` 固定；不能按阶段动态改返回长度。阶段头只能在 chunk 边界触发下一次 `get_action` 的行为，不能中途打断。
- 若想更紧的阶段对齐，选 `T=5`；若 RTT/推理延迟高，选 `T=8` 或 `T=10`。用 G7 消融。
- `reset_plan()` 只是清空内部 plan cache；不重置模型权重/其他端口。

### 3.5 规范系发现与估计

#### 离线：轨迹对齐发现（self-supervised）

对每个任务/子阶段：

```
输入：episodes 的绝对 EE 轨迹 T_BE(t)
初始化：视觉受器位姿 F_e
重复：
  canonical_i = { F_e_i^{-1} T_BE_i(t) }
  参考 = medoid(canonical_i) 或 DTW 平均
  对每条 i：F_e_i = argmin_F Σ_t d(F^{-1} T_BE_i(t), 参考(t))
  收敛
输出：F 模板、参考轨迹、每 episode 的 F_e
```

- `d` 用位置 + 旋转测地距离；Procrustes/ICP 求解。
- 对对称物体，轨迹对齐可以消歧 yaw。
- 子阶段可以有不同 F：抓取阶段以物体为 F，放置阶段以受器为 F。
- 这个算法不需要物体 6D 标注，也不依赖完美视觉；视觉只做初始化。

#### 在线：视觉 + 跟踪 + 回退

- 头双目 rectified：`cv2.StereoSGBM` 或轻量立体网络（若用网络，必须并入同一 checkpoint 或证明不是第二个策略）。
- 深度 → 点云；RANSAC 桌面平面；去掉桌面。
- 受器分割：
  - 颜色/几何/凹性/边缘；或
  - 同一 checkpoint 的 VLM grounding 头输出 2D box/keypoint；或
  - 离线模板 + ICP。
- 位姿：PCA/ICP；对称物体用轨迹先验消歧。
- 跟踪：上一帧 `T_BF` + 点云配准 + 光流；置信度 = 内点率、重投影误差、时序一致性。
- 回退：低置信度用上一帧；持续低用 `F=B`。
- 训练时 frame randomization：随机扰动 F、随机选 F（受器/桌面/物体）、随机回退 base。

### 3.6 阶段头与调度

#### 标签生成

1. 官方 `score_steps` 给有序阶段。
2. 夹爪开合事件：`|Δgripper| > threshold`；抓取/放置循环。
3. EE 运动阶段：approach / grasp / lift / transport / place / release；用速度/高度/夹爪状态分段。
4. 多物体任务：每个 grasp-place 循环对应一个阶段；按 rubric 顺序分配。
5. 无夹爪事件（开盖、拉拉链、倒药、针管）：视觉变化 + 人工 20 条/任务种子；或用 rubric 文本 + VLM 伪标注。
6. 阶段头：VLM pooled feature + state + frame pose → phase logits + completion logits。
7. 伪标注：高置信预测扩展；人工抽检。

#### 调度

```
if c[phase] > 0.8 for 3 chunks:
    phase += 1
    replan = True
elif frame_jump > 0.03 m or 5 deg:
    relocalize = True
elif no_progress for 4 chunks:
    retry = True
```

- 阈值按任务/阶段调；接触阶段更保守。
- 阶段头只做门控；动作仍由 WLA 生成。
- 若阶段头不可靠（G2 不过），只做可视化/诊断，不控制。

### 3.7 安全/后处理

- `clip_to_stats`：用 `meta/stats.json` 的 min/max（或 per-task 统计）裁剪 EE/pivot/gripper；HangCup 夹爪 0–4.5，pivot 高度 0.654–0.74，pitch 0.15，vw ±0.8。
- `nan_guard`：NaN/Inf/形状错误 → 用 `last_safe` 或零动作；记录日志。
- 每个 chunk 检查 `meta.token`；token 不匹配立即报错，不执行。
- `action_chunk_size` 与返回 shape 必须严格一致；dtype `float32`。
- 180s 时限：长任务（Toolbox 平均 37.6s）有充足余量；不要为了低延迟牺牲成功；chunk=5 的 RTT 折中用 G7 测。
- 延迟记录：adapter、frame、model、postprocess、queue；evaluator 也会记录。

### 3.8 与 CHUNK-SERVO 合并

| 第 12 轮 | 第 13 轮 |
|---|---|
| 30 步规划 + 5 步视觉伺服 | 保留；SCOPE 的 action plan 仍是 30 步，返回 5 步 |
| DG-KEYFRAME 演示检索 | 保留；作为规范系模板/目标库 |
| 数字孪生标定 | 缩权：只做相机/延迟/安全边界 |
| C1/C2/C3 合规 | 保留 |
| 任务组合/单任务通道 | 保留；升级为 5×32 矩阵 |
| 腕部无内参 | 删除；用 `meta/info.json` 内参 |
| 榜首<30% 真实 | 删除；公开榜单是预览 |
| 固定 5 步足够 | 升级：5 步 + 阶段头 + 规范系 |

## 4. 训练与数据

### 4.1 数据管线

1. 下载 32 个挑战 repo（约 811GB）；先下 6 个代表任务做管线，再扩全量。
2. 读取 LeRobot v3：四路视频、state、action、pivot、stats。
3. 绝对 EE 轨迹：`action.left/right_ee_pose_gripper_base`；当前 state：`observation.state.*`。
4. 规范系发现：离线轨迹对齐 + 视觉初始化；输出每 episode `T_BF` 和 canonical state/action。
5. 进度标签：rubric + 夹爪/运动事件 + 人工种子 + 伪标注。
6. 训练样本：`(images, canonical state, frame pose, phase, canonical action chunk)`。
7. 验证：留出 episode；按任务/物体/位置分层；不要随机打乱导致泄漏。

### 4.2 规范系标注/发现

- 优先用轨迹对齐（无标注）；视觉只做初始化。
- 每个任务 5–20 条 episode 做人工抽检；如果 canonical 轨迹方差不降，检查 F 定义。
- 对多受器任务（水果分类 3 个盘子），每阶段一个 F；阶段头选择。
- 对无受器任务（叠毛巾、开锁），F 用物体初始位姿/桌面；回退 base。
- 保存 `F` 模板、参考轨迹、置信度；在线用最近邻/ICP 匹配。

### 4.3 进度标签

- 每任务 2–5 阶段；94 个总阶段。
- 人工种子：20 条/任务 ×32 = 640 条 episode 标注（约 5–10 小时工作量）。
- 自动扩展：夹爪事件 + 运动阶段 + 伪标注；人工抽检 5%。
- 阶段头训练：类别平衡；时间平滑； completion 用 BCE；phase 用 CE/ordinal。
- 评估：phase accuracy/F1、completion calibration、边界误差（帧）。

### 4.4 损失

```
L = L_flow(a_F, a_F*) + λ_prog L_prog(phase, completion)
    + λ_frame L_frame(T_BF, T_BF*)       # 若 frame 头可训
    + λ_base L_flow(a_B, a_B*)           # 可选：回映射一致性
```

- `L_flow`：WLA 的 flow matching（canonical absolute action）。
- `L_prog`：phase CE + completion BCE。
- `L_frame`：仅当 frame 头在同一 checkpoint 内；否则用经典 CV，不加。
- `L_base`：可选；让 canonical 动作回映射后与 base 动作一致，稳定训练。
- 归一化：canonical action 重新统计 mean/std；per-task vs global 消融。

### 4.5 课程/增强

- 单任务 → 多任务；Easy → Medium → Hard。
- frame randomization：随机扰动/随机选择 F；随机回退 base。
- 物体替换：用 72 个相关 repo 的同技能数据；或 3D 资产替换/外观增强。
- 背景/位置/干扰物：图像增强 + 场景随机化；不要只靠颜色。
- 动作噪声：在 canonical action 上加小噪声，模拟 frame 误差；训练回映射鲁棒性。
- 长程：优先 4–5 步任务；阶段边界过采样。

### 4.6 资源估算

| 项 | 估算 |
|---|---|
| 存储 | 32 repo 约 811GB；72 repo 更大；先代表任务 + 流式 |
| 微调 | 1×24GB 可跑 action head；建议 1–2×A100 80GB 加速 |
| 推理 | 1×24GB 单模型；N 端口共享/队列；按延迟实测 |
| 规范系 | CPU/轻量 GPU；SGBM ~20–50ms/帧；跟踪 ~5–20ms |
| 标注 | 640 条 episode 种子；5–10 人时 |
| 周期 | 规范系 2–3 周；微调 1–2 周；阶段头 1–2 周；评测 2 周 |

## 5. 实验设计

### 5.1 G0–G7

| 门 | 问题 | 通过标准 |
|---|---|---|
| G0 | 接口/动作适配 | 32 任务单步 shape/dtype/token 全过；RGB/BGR、rpy→rot6d、pivot/gripper clip 正确；reset 隔离；延迟可接受 |
| G1 | 规范系发现 | 离线 canonical 轨迹方差显著下降；在线 frame 误差/置信度可测；回退 base 不崩 |
| G2 | 阶段标签 | 抽检 phase F1 > 0.8；completion 校准误差可接受 |
| G3 | 离线动作 | canonical absolute action 的 MSE/DTW 优于 base absolute；回映射误差小 |
| G4 | 单任务 A/B | WLA baseline vs SCOPE-Frame vs +Progress；至少 3 个代表任务、20–50 trials，success 或 step score 稳定提升 |
| G5 | 泛化矩阵 | 未见物品/人为干扰轴提升，位置/背景/干扰物不回归 |
| G6 | 全量提交 | 32 任务无接口失败；success/step 不低于 baseline；失败可分诊 |
| G7 | 消融 | frame vs base；absolute vs relative；per-task vs global norm；chunk 3/5/8/30；progress on/off；物体替换数据 on/off |

### 5.2 单任务通道协议

- 选 6 个代表任务：T01（未见物体+挂钩）、T05（双手+网线）、T12（接触+锁）、T16（形变+5 步）、T26（插入+精密）、T30（小物体+多钉）。
- 每条件 20–50 trials；先 baseline，再 SCOPE-Frame，再 +Progress。
- 若通道允许，固定初始位置/物体做配对；否则随机化并记录分层。
- 指标：success、step score、per-phase completion、latency、intervention recovery time。
- 不用公开榜单的合成 step score 做比较；用 evaluator 返回的真实 step score（若单任务通道给）。

### 5.3 消融

1. A0：WLA base + adapter（base 系绝对动作）。
2. A1：canonical state only（相对动作不变；预期小）。
3. A2：canonical state + canonical absolute action（SCOPE-Frame）。
4. A3：A2 + progress head/scheduler（SCOPE）。
5. A4：A3 + 物体替换数据。
6. A5：A3 + frame randomization。
7. A6：A3 + CHUNK-SERVO 末端伺服。
8. 动作空间：EE vs joint（若 IK/joint head 可行）。
9. chunk：3 / 5 / 8 / 10 / 30。
10. 归一化：per-task vs global。
11. frame：视觉 vs 轨迹对齐 vs 真值（上界）。
12. progress：无 / 仅诊断 / 控制。

### 5.4 指标/统计

- 主指标：32 任务平均 success `P`；次指标：平均 step `S`。
- 泛化：`P_a`、`S_a`（5 轴）；per-task 矩阵。
- 阶段：phase F1、completion calibration、阶段边界误差。
- 执行：latency p50/p95、timeout rate、NaN/clip rate、reset leakage。
- 统计：task-level paired bootstrap 10k；95% CI；不要只报均值。
- 样本量：官方 10 trials/task；单任务 20–50；必要时 100 做小效应。

### 5.5 任务组合

- 等权：每个任务 1/32；边际收益 = `ΔP/32`。
- 先修 2–3 步任务（25/32）：成功率高、阶段少、容易拿满分；但不要忽视 4–5 步任务的 7/32。
- 未见物品/人为干扰各占 20% trials；SCOPE-Frame/Progress 应优先在这两轴涨点。
- 位置/背景/干扰物占 60%；用数据增强/感知鲁棒性。
- 代表任务先做；全量矩阵后按 `q_t×Δ/cost` 分配。
- 先交安全基线；SCOPE 逐步替换；每次提交只改一个变量，保留回滚。

### 5.6 失败模式分诊

| 现象 | 可能原因 | 检查 |
|---|---|---|
| 抓不到 | 物体分割/规范系错；夹爪范围 | frame 置信度、gripper clip、腕部图 |
| 抓到但放不准 | canonical action 误差；受器 frame 错 | 回映射误差、受器点云 |
| 早期成功、最后失败 | 阶段头未前进/未重试 | phase logits、chunk 边界 |
| 人为干扰后继续旧动作 | frame 未更新；进度未检测 | frame jump、perturbation detector |
| 透明物体失败 | 双目深度缺失 | 腕部近景、多视角、回退 |
| 长任务超时 | chunk 太大/重试太多 | latency、chunk size、retry 策略 |
| 接口失败 | RGB/BGR、shape、token、reset | G0 日志 |

## 6. 风险与合规

### 6.1 单模型合规

- SCOPE-Frame：经典 CV（SGBM/RANSAC/PCA/ICP）不算第二个学习模型；若用 SAM/Detector/立体网络，必须并入同一 checkpoint 或放弃。
- SCOPE-Progress：同一 checkpoint 的辅助头；不单独部署第二个策略。
- Scheduler：确定性代码；不调用外部模型。
- 规则禁止“混合多个模型一起测试”；我们的系统是一个模型 + 确定性控制器；与 CHUNK-SERVO 的 C1/C2/C3 合规一致。
- 若评审认为经典 CV 也算“模型”，退化为纯几何/阈值版本；仍保留规范系思想。

### 6.2 技术风险

- 规范系估计误差：透明/反光/形变/遮挡；回退 base；训练 frame randomization。
- canonical absolute action 对 frame 误差敏感：加噪声训练；置信度低回退；不要硬用。
- 阶段头噪声：先诊断后控制；G2 不过门不控制。
- 物体替换数据不足：72 repo 覆盖有限；用外观/几何增强；不要过拟合颜色。
- 双臂/接触：WLA 的 lower_body/pivot 语义未完全验证；单任务通道先探针。
- 计算/存储：811GB；先子集；流式读取；特征缓存。

### 6.3 评测风险

- 公开榜单合成；不要优化/引用为 SOTA。
- 官方 10 trials/task 噪声大；单任务通道做更多 trial。
- 官方 step score 的精确计算未公开；用 rubric 近似 + 单任务通道校准。
- 评测硬件/相机可能与数据集有差异；内参/分辨率需验证。
- 评测端可能记录延迟/动作统计；不要用异常动作刷分。

### 6.4 竞赛风险

- 先交安全基线，避免接口/合规失分；再逐步替换 SCOPE。
- 不要 32 个任务各训一个策略；规则不允许。
- 不要等“完美模型”；公开榜单是预览，真实提交窗口/排名规则以官方为准。
- 保留回滚：每次提交一个变量；记录 commit/checkpoint/token。
- 任务组合按边际收益，不按公开榜单难度。
