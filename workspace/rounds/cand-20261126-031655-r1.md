## 1. 两个灵感的第一性原理

### 灵感 1 ·「灵巧操作」→ 不是手指自由度，而是「双臂协调 × 接触精度 × 长程记忆」

**直觉**：看到「Dex1」，第一反应会把它当成多指灵巧手（in-hand 重定向、指尖触觉、抓取流形）。但数据口径必须纠正这一点：G1 的 Dex1 夹爪只有 **1 个通道（5.5→0.0，张开→闭合）**，观测里也没有触觉与力矩。因此本赛题的「灵巧」是**任务级灵巧**：两条 7-DoF 臂 + 两个 1-DoF 夹爪，在长时序里做多物体、接触丰富、含关节/可变形物体的操作。把它误判成「手指灵巧」，会浪费整个赛季去打磨用不上的自由度；而真正稀缺的是**协调、接触状态与记忆**。

**严谨定义（灵巧操作四维）**：把本赛题的灵巧操作分解为可测量、可分别干预的四个维度：
- **D1 双臂协调**：两手共享同一物体参考系，或发生物体交接（FoldTowel、ArrangeTestTubes、ClearPlates、SyringeWaterTransfer）；
- **D2 接触精度**：插入/旋拧/对准，误差预算毫米级（PlugInEthernet、PlugCharger、Unlock、OpenPillBottle）；
- **D3 关节/可变形状态**：物体状态不是 6-DoF 位姿，而是「部分—关节—拓扑」（ZipUp、FoldTowel、PackBag）；
- **D4 长程记忆**：物体被放入容器/遮挡后，仍需知道它在哪、是否放对（PackBag、StoreEarphones、ToolboxStorage）。

榜单证据与四维对齐：最难簇集中在 D2（Plug In Ethernet 17.7、Unlock 20.1）与 D3（Zip Up 23.4、Fold Towel 24.1），而不是单纯的「抓不到」。这暗示瓶颈在**状态与接触**，不在策略容量。

### 灵感 2 ·「同步定位与建图」→ 从「静态地图」到「被自己动作改变的动态物体地图」

**直觉**：第 3 轮把 SLAM 译成「状态层」（SceneState）：估计目标位姿、维护场景图、扰后重定位。这解决了「世界变了但模型不知道」。但操作还有一个 SLAM 原生问题没被覆盖：**地图是被机器人自己的动作改变的**。机器人把杯子放进柜子、把药水抽进注射器、把毛巾对折——每个动作都让地图过期。经典 SLAM 的答案是动态 SLAM / 物体级 SLAM / 变化检测 / 遮挡持久性；这些恰好对应 D3+D4。再叠加「失败偏早期」的证据：问题往往不是最后一步没对准，而是**一开始就没定位准、没关联对、没记住**。

**严谨定义（物体级动态地图）**：把场景从静态位姿地图 `M=(T,D,F)` 升级为**物体级动态地图** `M_dyn = (O, A, C)`：
- `O`：物体地标集，每个带身份 `id`、位姿 `x̂`、协方差 `Σ`、静态/动态标签 `s`、最后可见时刻 `τ`；
- `A`：数据关联，允许多假设（防相似物体身份互换）；关联错误是第 3 轮「地图毒化」的真正机制；
- `C`：容器/遮挡关系（物体在哪个容器、最后可见时刻、置信随遮挡时间与动作的衰减）。
在 `M_dyn` 上再定义**可观测性地图**：对每个路标 `w` 与状态分量 `c`，给出 `o_{w,c}`（协方差条件数/Fisher 信息/检测置信的复合），把「估计 / 探测 / 伺服 / 跳过」做成路由。这就是 SLAM 的 observability analysis 直接迁到操作：**先问能不能看见，再问怎么控制**。

## 3. 设计原则（新增 P13–P15，接第 1–3 轮 P1–P12）

- **P13（相位路由）**：计算与状态建模按「失败相位」分配——低 step-success gap 的任务优先补早段（定位/关联/抓取），高 gap 任务才补末段（放置/插入伺服）。禁止对所有任务平均用力。
- **P14（可观测性优先）**：只建可观测、可校准的状态分量；不可观测时走「探测（必须先过 L13 记账）或退化链」，不得用隐式推断冒充状态。
- **P15（场景随动作更新）**：地图更新必须以动作为条件；遮挡物体保留身份与最后位姿，重观测时只做重定位、不做新物体创建。

## 3. 新增 IP 详述

### IP-17 · ObjectPermanenceMap 物体级动态地图 + 放置核验（P0，新）

- **动机**：D4（长程记忆）在容器类任务里被结构性低估。物体一旦放进柜子/包/工具箱，就被遮挡，终态不可见；端到端策略只能靠「最后一帧猜」，而失败恰恰偏早期（F2/L14），于是「做到一半忘了自己在干什么」。物体级动态 SLAM 是几十年验证过的补丁。
- **与现有方案差异**：第 3 轮 SceneState 只维护**单个目标位姿**，不处理「物体被自己放进容器 → 地图过期」。IP-17 增加：①物体地标集 + 多假设数据关联；②静态/动态标签（桌面/柜体静态，被操作物动态）；③容器关系与遮挡持久（最后可见时刻 τ、置信衰减）；④**放置核验**：动作历史 + 进入容器的几何事件 → 输出「已放入 / 未放入 / 不确定」，而不是从被遮挡画面硬判。
- **技术可行性**：高。检测 + 匈牙利关联 + 简单运动模型即可；核验是规则 + 少量标注。无新模型、无新数据依赖。
- **资源**：数据=32 集阶段标注 + 从 Dex1 同族任务（Store_/Toolbox_/Cup_Storage 等）抽容器片段；算力=小（低频 + 事件触发）；接口=无新增提交字段。
- **落地步骤**：①定义 `M_dyn=(O,A,C)` 与容器关系 schema；②关联最小实现（外观 + 位置 + 多假设）；③动作触发地图更新（抓取/释放/进入容器事件）；④放置核验状态机；⑤接入 IP-06 评测作为「核验准确率」切片。
- **风险**：相似物体身份互换（水果分拣、试管）→ 多假设 + 几何/接触确认；遮挡时间过长导致置信退化 → 显式「不确定」而非硬猜；Dex1 与挑战域差 → 只做同族预训练。

### IP-16 · BimanualState 双臂相对状态 + 交接检测（P1，新）

- **动机**：D1（双臂协调）是 Dex1 语料的固有形态（大量双手机器人任务），但 1-DoF 夹爪下最难的往往是「两手相对关系」而非单臂绝对位姿。G1 带腿/腰，基座漂移是共模误差；相对位姿能抵消共模（L15）。
- **差异**：第 3 轮状态层输出绝对目标位姿；IP-16 增加 `T_LR = T_L^{-1}T_R`、物体在左右手系的 `T_LO/T_RO`，以及**交接事件检测**（物体抓握归属从 L 切到 R）。
- **可行性**：高。左右 EE 位姿已在观测中；只需相对变换 + 协方差传播 + 规则检测；零训练。
- **资源**：近零；复用 IP-13/06。
- **步骤**：①相对变换与协方差（L15）；②共享物体系；③交接事件规则（一方释放 + 另一方闭合 + 物体位移连续）；④协调残差接入断言/介入；⑤E635。
- **风险**：独立噪声大时相对反而更差（L15 条件）→ 用协方差自适应选择绝对/相对；交接误检 → 保守阈值 + 多帧确认。

### IP-18 · InsertionGuard 精密插入 / 卡滞检测（P1，新）

- **动机**：最难簇（Plug In Ethernet 17.7、Plug Charger 25.6、Unlock 20.1、Syringe 24.6）全是 D2 接触精度；且无力/力矩通道，只能靠视觉 + 本体微动。
- **差异**：IP-09 的伺服是「到点即停」，不处理「对准了但插不进/卡住」。IP-18 是插入相位的专用子策略：视觉对准（孔/插座关键点）→ 微动探针（小步逼近，检测位移停滞/回弹）→ 卡滞判定 → 退出并重对准/换姿态。
- **可行性**：中高。视觉伺服与 peg-in-hole 搜索是成熟件；难点在无力觉下的卡滞判定（用本体指令-实际位移差做代理）。
- **资源**：小算力；标注从 Plug/Unlock 片段半自动抽取。
- **步骤**：①孔位关键点检测/模板；②对准伺服增益；③微动探针 + 停滞/回弹检测；④三段响应（继续/退避重对准/换姿态）；⑤E639。
- **风险**：关键点误检 → 多帧 + 置信门限；探针吃步骤分 → 过 L13 记账，只在插入/release 相位启用；过拟合少数任务 → 只保留最保守动作集。

## 5. 符号与定义（新增 U19–U21；U1–U18 沿用第 1–3 轮）

- **定义 U19（物体级动态地图）**：`M_dyn = (O, A, C)`。`O={o_j}` 为物体地标，`o_j=(id_j, x̂_j, Σ_j, s_j, τ_j, m_j)`（位姿、协方差、静态/动态标签、最后可见时刻、外观摘要）；`A` 为数据关联（多假设，返回关联熵作为不确定度）；`C` 为容器/遮挡关系（`inside(obj, container)`、置信）。地图更新算子 `M_{t+1}=U(M_t, a_t, obs_t)` 必须以动作 `a_t` 为条件。
- **定义 U20（可观测性地图）**：对路标 `w` 与状态分量 `c∈{target_pose, contact, articulation, bimanual_rel, inside_container}`，定义 `o_{w,c} ∈ [0,1]` 为可观测性（协方差条件数、检测置信、遮挡时长的复合）。路由 `ρ(w,c) ∈ {estimate, probe, servo, skip}`；`estimate` 仅在 `o≥o_min` 时允许（P14），否则走 `probe`（须过 L13）或 `skip`（退化链）。
- **定义 U21（双臂相对状态）**：`T_LR = T_L^{-1}T_R`，协方差 `Σ_LR = J(Σ_L,Σ_R,Cov_LR)J^T`；物体相对各手的 `T_LO,T_RO`；协调残差 `r_b = log(T_L^{-1}T_R) − log(T̂_LR)`；交接事件 `h` = 抓握归属从 L 切到 R（或反向）。

## 6. 关键算法骨架（新增片段；主体沿第 1–3 轮 `UniBotSAGEPolicy`）

```python
# ===== IP-17: 物体级动态地图 + 放置核验 =====
class ObjectMap:
    def __init__(self):
        self.O, self.C = {}, {}          # U19: 地标 + 容器关系
        self.H = []                      # 关联多假设

    def update(self, obs, action):
        dets = self.detector(obs)
        assoc = self.associate(dets, self.O)          # 外观+位置+多假设
        for j, cands in assoc.items():
            if self.entropy(cands) > TAU_ASSOC:       # 关联不可信 → 不覆盖
                continue
            self.O[j] = self.kalman_update(self.O[j], cands[0])
        if is_release(action):
            for o in self.grasped(action):
                self.C[o] = inside_target(o, obs)     # 动作条件地图更新 (P15)
        for o in self.O:
            self.O[o].conf *= decay(obs.t - self.O[o].tau)   # 遮挡持久衰减
        return self.O

    def verify_placement(self, obj, target):
        if obj in self.C:                              # 进入容器事件已知
            return ("placed", self.C[obj].conf)
        if self.O[obj].conf < TAU_OCC:                 # 长期不可见
            return ("uncertain", self.O[obj].conf)     # 不硬猜
        return ("not_placed", 1 - self.O[obj].conf)

# ===== U20: 可观测性路由 (P13/P14) =====
def route(waypoint, obs, state):
    for c in waypoint.state_deps:                      # target_pose/bimanual_rel/...
        o = observability(waypoint, c, state, obs)     # 条件数/置信/遮挡
        if o < O_MIN and c in PROBE_WHITELIST:
            return "probe"                             # 须过 L13 记账
        if o < O_MIN:
            return "skip"                              # 退化链
    return "estimate"

# ===== U21: 双臂相对状态 =====
def bimanual_state(state):
    TL, TR = state.ee("left"), state.ee("right")
    TLR = inv(TL) @ TR
    Sigma = prop_cov(state.Sigma_L, state.Sigma_R, state.Cov_LR)
    r_b = log_se3(TLR) - log_se3(state.TLR_hat)
    return TLR, Sigma, r_b

# ===== IP-18: 插入 / 卡滞检测 =====
def insertion_step(wp, obs, state):
    kp = detect_hole(obs.wrist, wp.target)             # 孔/插座关键点
    if kp.conf < TAU_KP:
        return ("search", spiral_probe(obs))
    err = kp.pose - state.ee_pose
    if stalled(cmd_history=state.cmds, actual=obs.ee, k=K_STALL):
        return ("jam", retreat_and_realign(obs))        # 卡滞 → 退避重对准
    return ("servo", visual_servo(err, wp.gain))
```

## 7. 推导（新增引理 L14–L16；L1–L13 沿用第 1–3 轮）

**引理 L14（由步骤分反推失败相位）** 设步骤分按「成功 episode ≈ 满分 100」归一，任务 `t` 的成功率 `p_t`、平均步骤分 `s_t`，失败 episode 的平均完成度 `F_t`（同单位）。则 `s_t = 100·p_t + (1−p_t)·F_t`，故 `F_t = (s_t − 100·p_t)/(1−p_t) = g_t/(1−p_t)`，其中 `g_t = s_t − 100·p_t` 即步骤分—成功率差。由快照：Stack Cups `F≈14.8%`、Unlock `≈8.5%`、Plug In Ethernet `≈7.3%`；对模型平均，MolmoAct2 `F≈13.2%`、GR00T N1.5 `≈9.6%`。⇒ **失败 episode 平均只完成约 7–15% 的步骤 rubric，失败主要发生在极早期/前段，而非最后一厘米**；难度越高 `g_t` 越小（`corr(success, g)=0.999`），说明**越难的任务越早失败**。∎（口径未被规则手册确认；若成功 episode 步骤分≠满分，此反推需重标定——本轮最大风险。）

**引理 L15（相对状态的共模误差消减）** 设左右 EE 位姿误差 `e_L,e_R`，相对误差 `e_rel = e_L − e_R`，`Var(e_rel)=σ_L²+σ_R²−2ρσ_Lσ_R`。若基座/腰漂移是共模（`ρ>0`），则相对状态方差可比单臂绝对方差更小；特别地当 `σ_L=σ_R=σ` 时 `Var(e_rel)=2σ²(1−ρ)`，`ρ→1` 时趋近 0。⇒ **在带腿/带腰的 G1 上，bimanual 任务应优先用相对状态；当两臂误差独立（ρ≈0）时相对反而更差**，故需按 `Σ` 自适应选择。∎

**引理 L16（可观测性路由的收益上界）** 为状态分量 `c` 增加估计器带来的期望收益上界为 `I(c; obs)/cost`（互信息/单步成本）；当可观测性 `o_{w,c}<O_MIN` 时，`I(c;obs)` 不足，必须先付探测成本 `s_p`。由 L13，探测值得做当且仅当 `q·(r+Σ s_i(1/γ−1)/p_i) > s_p`。⇒ **不可观测的状态分量不应强行建模（P14）；应路由到探测（若过 L13 账）或退化链**，否则只是把噪声包装成「状态」。∎
