# 第 8 轮 · SIGHTLINE：路径要可见，也要像演示；先用首败定位，再押跨轴杠杆

> 检索/复核日期：**2026-10-26（UTC）**。赛事身份不变：宇树科技 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。状态文件从第 7 轮续起，本轮对应外部灵感循环第 6 轮，标题按状态文件编号为第 8 轮。三个灵感词是「路径规划」「需求洞察」「视觉感知」。
>
> 本轮先做了三件不讨喜但必须做的事：**把规则读细、把榜单打假、把第 7 轮的“步骤分杠杆”重算**。结论是：第 7 轮“终局放置是成功闸门”仍然成立，但“放置占约 60% 步骤分所以是大头”必须降级——官方排名是**总平均成功率优先，步骤分只在成功率相同时才起作用**；用户看到的“榜首不到 30%”也不是真实榜单，而是首页/JSON 里 `gen_leaderboard.py` 生成的占位条目。真正被低估的缺口是：**我们不知道“第一次失败”发生在哪一步；而 2026 年的证据一致指向中段路径与视角，而不是再训一个更大的 VLA。** 于是本轮的主判断是：**先用首败归因（FFA）定位，再把预算押到 SIGHTLINE——一条既避开干扰物、又让冻结 VLA 看到的画面像训练数据的路径。路径规划不再只是“无碰撞可达”，而是“可见 + 在演示视觉流形内”。**

## 0. 本轮核实：六个会改变预算的事实

### 0.1 规则：320 次真机 trial，成功率优先，步骤分只破平局

官方参赛手册（飞书，2026-10-26 复核，[S1]）写得很清楚：

- 每个任务执行 **10 次**独立运行；10 次里包含 5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰），**每类各 2 次**。所以完整评测是 **32 × 10 = 320 次真机 trial**。
- 实时榜单按 **32 个任务的总平均成功率**排序；成功率相同，按总平均步骤分排序；仍相同，提交日期早的靠前。
- 单次 trial 最大 **180 秒**，超时记失败，并按执行情况计算步骤分。
- 只设通才模型赛道：**同一模型完成全部 32 个任务，不得混合多个模型**；模型类型不限（World Model、VLA 均可）。
- 选手自行部署模型，官方通过远程 API 接入；另有不计分单任务调试通道，需预约时段。

这条规则直接改写第 7 轮的算术：**步骤分不是主目标，部分完成只在“所有成功者打成平手”时才有用。** 因此“终局放置 +15pp ⇒ 总分 +7~10pp”的推导不成立；正确的量是“这个干预能不能把一次 trial 从失败翻成成功”。

### 0.2 榜单：首页有 8 行数字，但它们是占位，不是真实成绩

我同时抓了四个入口（2026-10-26，[S2][S3][S4]）：

- `index.html` 与 `leaderboard.html` 都渲染了 8 行：MolmoAct/DexHacker 29.7%、WALLOSS/Generalist Robotics 28.5%、DreamZero/World Model Lab 27.9%、spirit/VLAGO 25.9%、DM/Embodied AI Institute 23.5%、PI/RoboReasoner 22.8%、GigaBrain/xembody 22.6%、gr00t/Humanoid Dynamics 20.5%。
- 但同一页脚标仍是「**即将发布 / Coming Soon**」。
- `leaderboard_data.json` 的 `generated_from` 仍是 **`gen_leaderboard.py`**；8 个模型 × 32 任务 = 256 条 `task_metrics`，数值平滑得不像真机。
- 新 `runs.html` 是 `256 / 256` 条记录；`details.html` 明确写「**测试视频占位，后续可替换为真实视频文件**」。

所以：**“榜首不到 30%”不能作为真实头部方案的证据，也不能用来做轴级归因。** 这些名字只能当“方法类型”的占位样本：3D/深度 VLA、通才 VLA、世界动作模型、混合推理。真正榜单发布后，第 7 轮的所有“占位先验”都要重跑。

### 0.3 数据：33,276 条、169 小时、32 个仓库；四路相机 + 两套 EE 坐标

- HuggingFace collection 有 32 个数据集，每个约 970–1,530 条；第三方统计为 **33,276 条、169 小时、约 811GB、18,282,246 帧、30fps、640×480、AV1、Apache 2.0**（[S5][S6]）。
- HangCup 实测 **1,043 条、194,564 帧**，`lastModified = 2026-10-14`；`meta/info.json` 直接给出 `camera_params`：头戴双目内参/畸变/立体校正，左右腕相机内参；`state_d435` 是 D435 相机位姿，`left/right_ee_pose_gripper_base` 与 `_torso` 两套坐标都在（[S7]）。
- 每条指令在 `meta/tasks.parquet` 里是 **5 条英文复述**，用 `@` 连接；SSG 的指令匹配要覆盖 32×5=160 条（第 7 轮已核实，本轮保持）。
- 数据结构是 LeRobot v3；动作有 joint 与 ee 两套、gripper、lower_body、pivot；观测没有显式深度图，只有**双目 RGB**，深度要从立体匹配或 `state_d435` 几何推。

这给 SIGHTLINE 两个硬条件：**头戴双目可以做米级 3D 重建；腕部相机是单目，但可以用图像统计（目标质心/尺度/遮挡率）建“图像空间视角流形”，不必先有腕部外参。** 这是降低工程风险的关键。

### 0.4 接口：chunk 在 handshake 固定，执行是开环的；延迟会被记录

`unibot_submission` README（v2，2026-08-21，[S8]）确认：

- `metadata.action_chunk_size` 在握手时固定；`get_action` 返回一个 chunk，**评估器按顺序执行完，直到下一次调用**。也就是说，chunk 内没有中途重规划；想闭环只能把 chunk 设小，或用小步长多次查询。
- 观测键是 `cam_left_high` / `cam_right_high` / `cam_left_wrist` / `cam_right_wrist`、双臂关节/EE、gripper、lower_body、`observation.language` 单字符串；`obs_delta_indices` 决定传哪些键、每键堆叠几帧；`image_resize` 自定。
- N 台机器人、N 个连续端口（8765 起）；**每步响应延迟及其稳定性会被记录**，官方可能随成绩展示。
- 不计分单任务调试通道存在，但次数/成本未公开。

这意味着：SIGHTLINE 不能是一个“每 100ms 重规划一次”的重型 MPC；它必须是**低频规划 + 高频小闭环**：每个 transit 段规划一次，chunk 内做路径跟踪/视角锁定，下一个 `get_action` 再评估是否重规划。

### 0.5 任务：32 项里 28 项终局是放置，但“首败”可能更早

`tasks_v2/<slug>/info.json` 的 `score_steps` 已公开（[S9]；T27 实测：放碗 1/2/3 分别 30/30/40）。按第 7 轮整理的 32 项：

- 难度 12 Easy / 12 Medium / 8 Hard；每项 2–5 步。
- 32 个终局步骤里 28 个是放置/插入/堆叠/闭合；另外 4 个是拔出/取出/翻转/倾倒（T05/T11/T12/T14）。
- 粗略分类：**多物体抓放/排序/整理约 18 项**（T02/T03/T04/T06/T08/T09/T13/T15/T17/T18/T20/T21/T22/T24/T25/T27/T28/T29/T30），**插入/闭合/拉链/塞入约 12 项**（T05/T07/T10/T12/T18/T19/T23/T26/T29/T31/T32/T09），**明显需要双手协调约 11 项**（T05/T09/T12/T16/T18/T19/T23/T29/T30/T31/T32）。
- 官方还逐任务给了 `human_1_note` / `human_4_note` / `unseen_object_3`（T27：human_1=「把粉色碗向下移动」，human_4=「叠了第二个之后拿下第二个」）。这些备注大多是“对某物体做一次 1-DOF 平移”或“完成一步后撤销”。

**但“终局是闸门”不等于“首败在终局”。** 一次 trial 可能死在：抓空、拿起后撞翻干扰物、路径上被人的手挡住、插入前视角丢了、拉链夹住、超时。第 7 轮把“终局放置”当唯一主目标，是把“闸门”误当成了“首败分布”。本轮把这个假设降级为待测项。

### 0.6 头部方法原型：四类模型，同一个缺口

占位数字不可信，但占位条目指向的四类公开方法都可查。它们的共同点不是“语义不够强”，而是**没有显式的 3D 路径层与视角层**：

| 占位条目 | 公开方法原型 | 公开事实（非 UniBot 成绩） | 可能瓶颈 | SIGHTLINE 能补什么 |
|---|---|---|---|---|
| MolmoAct/DexHacker 29.7% | MolmoAct2：Molmo2-ER + flow-matching action expert + 自适应深度 token | 单次动作约 180ms（base）/790ms（Think），LIBERO/H100；深度是 10×10 粗网格（[S10]） | 深度粗、无显式碰撞/路径、chunk 开环 | 双目 3D 路径 + 可见性约束；保留其深度推理 |
| WALLOSS/Generalist 28.5% | WALL-OSS-0.5：4B、20+ 本体、梯度桥接预训练 | 15 项真机任务平均进度 60.5%，强 zero-shot（[S11]） | 通才先验强、任务几何弱；视角敏感 | 演示流形内的路径，减少视角 OOD |
| DreamZero/World Model Lab 27.9% | DreamZero：14B 视频扩散世界动作模型 | 7Hz 实时闭环；新任务/环境 2× 泛化（[S12]） | 14B 重、世界模型会幻觉接触、无碰撞保证 | 确定性几何安全层，补世界模型的物理盲区 |
| PI/RoboReasoner 22.8% | π0.5：异构 co-training、开放世界 | 新家场景长程任务；作者自述受部分可观测/手臂遮挡/分心困扰（[S13]） | 遮挡、分心、无显式路径 | 可见性路径 + 重观察原语 |
| GigaBrain/xembody 22.6% | GigaBrain-0/0.7：世界模型数据 + RGBD + 具身 CoT | 37k 小时异构预训练；重（[S14]） | 重、延迟、CoT 慢；无路径层 | 轻量测试时路径层 |
| gr00t/Humanoid 20.5% | GR00T N1.5（NVIDIA） | 通才 VLA；具体 UniBot 表现未公开 | 通才策略、视角/动作 chunk | 模型无关 wrapper |

这张表的用法是：**如果这 8 个原型代表当前主流，那么“再训一个更大的 VLA”是正面竞争；“给任意一个 VLA 加一个几何/视角层”是侧翼竞争。** 后者更符合我们的小团队资源，也更容易在 320 次 trial 里做出可归因的增益。

## 1. 三个灵感词，各自钉到本轮事实上

### 1.1 需求洞察：不是“更多语义”，是“首败在哪 + 视角是否在分布内”

“需求洞察”在本轮不是指用户访谈，而是指**把评测的真实需求拆开**。我把它拆成三层：

**第一层：榜单需要什么。** 成功率优先，步骤分只破平局；320 次 trial，每任务只有 10 次。于是：

```text
排名 = mean_t P_t(成功)
P_t(成功) = P_t(首败 = 无)
```

一次干预只有把某次 trial 的“首败”消除，才会改变成功率；只把失败 trial 的步骤分从 20 提到 40，对排名几乎没用（除非所有成功者同分）。**所以第一步不是选模型，是测首败分布。**

**第二层：模型需要什么。** 冻结 VLA 的能力边界由训练分布决定。2026 年两组证据很刺眼：

- WARP-VLA：腕部视角扰动会把 π0.5 的平均成功率从 39.2% 打到 78.3% 的另一侧——论文的修法是把视角鲁棒性学进模型（[S15]）。
- ActiveAlign：把“主动把相机移过去看”直接前置到 π0.5，成功率从 46.3% 掉到 11.5%；原因是第一帧分布变了。经过“视角终点对齐 + 数据适配”后才到 72.7%（[S16]）。

这两条合起来说明：**“多看看”本身不是免费的；视角一变，策略就可能出分布。** 正确的主动视觉不是“随便找个能看见的位姿”，而是“找一个既看得见、又像训练数据的位姿”。

**第三层：团队需要什么。** 10 次/task 的噪声很大：p≈0.5 时，单任务标准误约 0.15；32 任务平均的理论标准误约 0.027。也就是说，**+5pp 的全局提升只有约 1.8σ，+2pp 基本测不出来。** 预算应该押在“能把一批任务从 0.1–0.4 翻到 0.5+”的干预上，而不是追求每个任务 +1pp。

于是“需求洞察”的产物是一个**首败归因 + 铰链任务选择**框架（FFA）：

```text
对每个 task t、泛化轴 a：
  p_t,a = 成功率
  m_t,a = 首败模式（抓取/路径碰撞/遮挡/放置/插入/时序/人扰/超时）
  f_m   = 该模式被干预修好的概率
  期望增益 ≈ (1 - p_t,a) × f_m / 成本
优先做：p 在 0.1–0.5、f_m 高、且同一干预覆盖多个 task 的格子。
```

这不是“选最弱的轴”，也不是“选最简单的任务”，而是**选“首败模式可修、且跨任务复用”的格子**。第 7 轮的“终局放置”只是候选模式之一，必须先被 FFA 证实。

### 1.2 路径规划：VLA 缺的是“中段”，不是“终点”

第 7 轮的 PGL/OPT 把终点做得很细：槽位→2D 锚点→6D 位姿；SVL 做落点闭环。但**从“抓住”到“放到”之间的中段**，仍然完全交给 VLA 的 2D 反应式策略。这个中段在本赛里恰好被三类扰动同时攻击：

- **干扰物轴**：桌上多出杂物，拿着物体的手臂/物体本身会扫到它们；一次碰撞可能把目标或容器撞走，后面全错。
- **位置轴**：起点/终点整体平移，演示里的直线/弧线不再适用；VLA 可能“看起来在走”，但路径擦着容器边缘。
- **人为干扰轴**：人会把物体移走/把已完成步骤撤销；模型需要重新定位、重新规划，而不是继续执行旧 chunk。

而演示数据里的中段是**干净的**：33k 条遥操作大多在无干扰的桌面完成，路径宽、障碍少。模型没见过“拿着碗从两个杯子之间穿过去”的负样本。**这就是分布缺口：语义没变，几何变了。**

路径规划在这里的角色不是“替代 VLA”，而是**给中段一个可检查的几何骨架**：

```text
抓取/接触段：VLA 主导（它擅长局部视觉伺服）
中段搬运：路径层主导（碰撞、可达、可见、演示流形）
终局放置：VLA + PGL/OPT + SVL 主导（精度/力控）
```

为什么现在可以做？因为 180 秒/trial 足够慢；因为头戴双目给了米级 3D；因为 G1 的 EE 动作空间允许我们直接给笛卡尔路点；因为路径规划是确定性代码，不需要第二个学习模型。**它不跟 VLA 抢“语义”，只补“几何与视角”。**

### 1.3 视觉感知：腕部相机既是传感器，也是路径的函数

在眼在手上（eye-in-hand）的设定里，**腕部相机的视角不是给定的，是被手臂路径决定的**。这带来一个第 7 轮没展开的杠杆：

- 同一目标，从正面接近和从侧面接近，腕部看到的纹理、遮挡、尺度完全不同；VLA 对后者可能没见过。
- 放置/插入时，目标槽位常常被夹爪、容器壁、或拿着的物体自己挡住；如果路径让它一直挡住，视觉伺服就失效。
- 主动把腕部移到一个“能看见”的位姿，可能正好把 VLA 推出训练分布（ActiveAlign 的 46.3→11.5 就是警告）。

所以视觉感知的正确问题不是“再上一个更强的检测器”，而是：

```text
给定任务/阶段，演示里的腕部视角分布是什么？
候选路径会把腕部带到这个分布的哪里？
如果偏离太远，是换路径，还是先做一个“重观察”再回来？
```

这导出了本轮的核心概念：**演示视觉流形（demo view manifold）**。它不是全局外观，而是**目标相对腕部相机的几何/图像统计**：目标质心、尺度、朝向、遮挡率、以及（若有外参）目标系下的相机位姿。它在不同背景、不同位置下都可比，正好对应本赛的背景/位置轴。

### 1.4 三个词汇合：SIGHTLINE

把 1.1–1.3 合成一句话：

> **先用 FFA 找到“首败是路径/遮挡”的任务；对这些任务，把中段路径规划从“无碰撞可达”升级为“无碰撞 + 目标可见 + 腕部视角在演示流形内”；用冻结 VLA 做接触段，用确定性路径层做中段，用重观察/重规划做人扰恢复。**

这套东西叫 **SIGHTLINE**：**Sight-Informed Geometric Path**。它的主张很窄，因此可证伪：

- 不是“更好的 VLA”；
- 不是“完整的 TAMP”；
- 不是“更多数据”；
- 是“**让冻结 VLA 走一条它看得见、也见过的路**”。

## 2. 为什么是现在：三条证据链

### 2.1 证据链 A：碰撞是 VLA 的已知盲区，而本赛的干扰物轴正打这里

- VLPSA（2026-09）用泊松安全函数 + CBF-QP 给 VLA 做全身安全滤波，在 SafeLIBERO 上把碰撞避免率从 23.1% 提到 91.2%，同时任务成功率不降（[S17]）。
- Multi-Link Safety Filtering（2026-09）用五个椭球覆盖夹爪/腕/前臂，碰撞率从 65.6% 降到 27.3%，safe-success 从 29.4% 提到 50.4%（[S18]）。
- CaSCo（2026-09）进一步指出：碰撞不是二元的，碰到纸箱和碰到玻璃杯的后果不同；要用语义风险 + 物理仿真预测级联碰撞（[S19]）。
- IMPACT（ICRA 2026）用 VLM 给物体打“可接触性”分数，做各向异性 A*，在密集 clutter 里找“可接受的接触”路径（[S20]）。

这些工作证明：**VLA 本身不保证不碰无关物体；而本赛的干扰物轴就是专门加无关物体。** 但它们大多只做“安全”，不保证“任务更快成功”。SIGHTLINE 要把“安全”变成“成功”：不只避开，还要选一条让后续放置更容易的路径。

### 2.2 证据链 B：主动视觉有效，但会带来第一帧分布问题

- RH-NBV（2026-10）在强遮挡下用滚动时域多步视角规划，ROI 覆盖率 63.8% vs 单步 34.2%，遮挡面召回 85.5% vs 7.4%（[S21]）。
- AWAM（2026-10）用“轨迹条件化的虚拟视角想象”给世界模型提供空间先验，在 LIBERO-Occ/RLBench-OG 上有效（[S22]）。
- ActiveAlign（2026-10）证明：直接把主动视角前置会给 VLA 带来 first-frame distribution sensitivity；必须让训练数据覆盖“视角终点”的状态（[S16]）。
- WARP-VLA（2026-10）证明：腕部视角的小扰动就足以让 π0.5 从 39.2% 掉到另一个量级；用 MoE 做视角专家可回到 78.3%（[S15]）。

这组证据的直接推论：**“能看见”不等于“能做好”。** 如果 SIGHTLINE 只优化可见性，它可能重蹈 ActiveAlign 的 46.3→11.5。必须加“演示流形”约束，让路径诱导的腕部视角仍然像训练数据。这是本轮的“反直觉点”，也是与现有 active perception 的最大差异。

### 2.3 证据链 C：路径级检索与规划已经成熟，缺的是“给 VLA 用”

- Tether（2026-03）用语义关键点对应把 ≤10 条演示的轨迹 warp 到新场景，在 12 个桌面任务上超过基础模型/预训练基线（[S23]）。
- RAGu（2026）用“语义过滤 + warp + DTW 检索 + flow-matching 引导”，把真实机器人成功率从 20% 提到 80%，且不改 VLA 权重（[S24]）。
- SDAR（ICRA 2026）做双臂桌面重排的 TAMP，在强纠缠任务上 100% 成功；但假设已知物体位姿、且是纯几何规划（[S25]）。
- 第 7 轮的 ICR/OPT 已经在做“检索 + 位姿迁移”，但检索的是**动作块/放置位姿**，不是**中段路径**。

所以技术栈是齐的：**检索给人味，几何给安全，VLA 给接触**。缺的是把三者接在一个 30Hz 的远程 API 里，并且不破坏单模型合规。

## 3. SIGHTLINE 一页纸

```text
┌────────────────────── Offline（33k 演示，无新数据）──────────────────────┐
│ 1. 任务/阶段切分（SSG 的 score_steps + 夹爪/EE 事件）                    │
│ 2. 演示视觉流形：每任务/阶段的目标相对腕部统计（图像质心/尺度/遮挡/朝向）│
│ 3. 路径库：每段 transit 的 EE 路点，存到目标/容器相对坐标               │
│ 4. 标定：头戴双目 3D；腕部优先图像空间，外参可选                        │
└──────────────────────────────────────────────────────────────────────────┘
                                   │
┌────────────────────── Online（一次 get_action 内）───────────────────────┐
│ obs（4 路 RGB + proprio + language）                                     │
│   ├─ 场景图：双目深度/平面/掩码/6D 位姿/占据栅格 + 人扰变化检测          │
│   ├─ 任务状态：SSG 指令→步骤；当前 phase（approach/transit/place/close）  │
│   ├─ 路径候选：K 条演示路径 warp + K 条 cuRobo/BiRRT* + 抬升绕行        │
│   ├─ 评分 J：碰撞风险 + 可见性 + 视角流形 NLL + 长度/时间               │
│   ├─ 选择：若 VLA chunk 的隐含路径 J 接近最优 → 用 VLA；否则路径接管    │
│   └─ 执行：chunk 内路径跟踪/视角锁定；下一 chunk 重评估；必要时重观察   │
│                                                                          │
│ 触发重规划：场景变化 > 阈值 / 可见性 < Vmin / 流形 NLL > τ / 人扰事件    │
└──────────────────────────────────────────────────────────────────────────┘
```

**目标函数**（每条候选路径 τ）：

```text
J(τ) = ∫ [ λ_c · C_col(q(t), payload, scene)
         + λ_v · (1 - V(target, wrist(q(t))))
         + λ_m · NLL_view(ξ(q(t)) | task, phase)
         + λ_l · ||ṗ(t)|| ] dt + λ_T · T(τ)

V = clip( A_mask · (1 - O) / A_ref , 0, 1 )
NLL_view = -log p(ξ | task, phase),  ξ = (目标质心, log 尺度, 朝向, 遮挡率)
```

- `C_col` 用夹爪+被持物体的 swept volume 对场景做连续碰撞检查；语义风险权重让“碰到纸杯”和“碰到玻璃杯”不同。
- `V` 用双目重建 + 光线投射算目标/容器在腕部图像里的可见面积；含机器人自遮挡。
- `NLL_view` 是 SIGHTLINE 的“反 OOD”项：候选路径诱导的腕部视角，必须落在演示分布内。
- `λ` 不学一个策略，只用离线演示做偏好校准（demo 路径应比随机路径 J 低）；这是确定性/轻量学习，不引入第二个策略模型。

**与现有工作的差异**：

| 现有工作 | 它做什么 | SIGHTLINE 的不同 |
|---|---|---|
| VLPSA / Multi-Link Safety | 用 CBF/椭球保证不碰 | 不只安全，还要选“让后续放置更容易”的路径；且把被持物体算进 swept volume |
| AWAM / ActiveAlign | 主动视角/虚拟视角，必要时微调 VLA | 不改 VLA 权重；把“视角”作为路径约束，而不是先移动再适配 |
| VMC / RH-NBV | 最大化可见性/信息增益 | 加“演示流形”项，防止可见但 OOD；路径级而非单视角 |
| RAGu / Tether | 检索/ warp 轨迹 | 对 warp 后的路径做碰撞/可见/流形评分，并允许几何候选补位 |
| SDAR | 纯几何 TAMP，假设已知位姿 | 用 VLA 做接触段；用双目/掩码处理未知位姿；只规划中段 |
| 第 7 轮 ICR/OPT | 检索动作块/放置位姿 | 检索的是中段路径；OPT 仍作为终点目标提供者 |

**不做什么**：不训练新 VLA；不做全 32 任务高保真孪生；不做布料/拉链全物理；不做运行时 MPC；不做每任务 LoRA。这些在第 7 轮已经被证明是预算黑洞。

## 4. 可证伪的实验计划

### 4.1 五个假设

| 编号 | 假设 | 判定 | 失败后的动作 |
|---|---|---|---|
| H1 | 在 4 个调试任务上，路径/遮挡类首败 ≥30% | 人工/半自动首败标注 | <15% → SIGHTLINE 降级，转抓取/插入 |
| H2 | 纯可见性路径（VAP）在视角敏感任务上不如 SIGHTLINE | A/B：VAP vs SIGHTLINE | 无差异 → 去掉流形项，保留 VAP |
| H3 | SIGHTLINE 在路径敏感任务上 +5pp 成功率，且 easy 任务不回归 >2pp | 调试槽 + 计分跑 | 不达标 → 回退到“仅安全滤波” |
| H4 | 每次 `get_action` p99 增加 <300ms，整局限时增加 <15% | 延迟日志 | 超标 → 降候选数/降感知频率 |
| H5 | 官方人扰剧本下恢复率 ≥50% | 调试槽回放 | <30% → 人扰只做“重启当前步” |

### 4.2 任务选择（铰链任务，不是最难的）

优先选“路径/视角首败概率高、且干预可复用”的任务：

- **T27 StackBowls**：3 个碗、终局堆叠、human_4 会撤掉第二个碗；路径碰撞/视角都敏感。
- **T24 ConveyorSorting**：传送带运动目标 + 人把物品放回起点；重定位/重规划。
- **T10 PlugCharger**：插排/插头插入；视角与末端精度。
- **T19 ZipUp**：拉链；腕部视角 + 闭合终局。
- 备选：T13 ArrangeTestTubes（细长物、遮挡）、T17 OrganizeStationery（多物体 + 合盖）、T02/T04（多水果排序）、T20/T25（堆杯）。

### 4.3 三级验证

1. **离线（W1–W3）**：33k 演示建流形；held-out 20% 测 NLL 的 OOD 检测 AUC；比较 demo 路径 / cuRobo 路径 / 随机路径的 J；在 Isaac Lab/MuJoCo 的 6 个任务上做相对比较（不做 sim2real 绝对承诺）。
2. **调试槽（W4–W6）**：每个大版本 1 个不计分单任务槽；T27 → T24 → T10（或 T19）；每个槽 10 次 trial，记录首败、碰撞、可见性、NLL、耗时。
3. **计分跑（W7–W8）**：最多 2 次；提交前 4h soak（N 端口、状态隔离、延迟 p99）；用分层贝叶斯模型估计全局效应，不用单任务均值吹牛。

### 4.4 统计

- 主指标：32 任务平均成功率。
- 次指标：首败模式分布、碰撞率、目标可见率、视角流形 NLL、p99 延迟、超时率。
- 用分层 logistic：`logit(p_t) = α + β·intervention + u_t`，`u_t ~ N(0, σ²)`；报告 95% credible interval。
- 预注册任务/假设；不看到结果后换指标。
- 320 trial 的全局 SE 约 2.7pp；+5pp 只有 ~1.8σ。所以要么在调试槽里做配对重复，要么把目标定在 +8–10pp 的子集增益，再靠分层模型外推。

### 5.2 主押注 I1：SIGHTLINE

- **动机**：中段是 VLA 最没有几何约束的一段；干扰物/位置/人扰三轴同时打这里；碰撞和遮挡会不可逆地毁掉 trial。
- **与现有方案差异**：不是“安全滤波”（只避碰），不是“主动视觉”（只找可见位姿），不是“轨迹检索”（只 warp），而是把**可见性 + 演示视角流形 + 碰撞**放进同一个路径评分；VLA 权重不动。
- **技术可行性**：双目 3D、URDF、cuRobo、SAM2/经典分割都是现成的；腕部流形可退化为图像统计，不依赖外参；chunk 固定但可以设小。
- **所需资源**：1×A100 做实时感知/VLA；CPU/GPU 做路径采样；8×H100 3–5 天做离线流形/标定；无需新数据。
- **落地步骤**：FFA→流形→场景图→路径候选→评分→执行→调试槽。
- **风险**：流形太窄导致无解；外参不准；延迟；单模型审计；H1 不成立。

### 5.3 主押注 I0：FFA 首败归因

- **动机**：第 7 轮把“终局”当首败，可能把预算押错；榜单又是占位；必须先测。
- **差异**：不按步骤权重分配，而按“第一次失败的模式”分配；用分层贝叶斯处理 10 次/task 的噪声。
- **可行性**：调试槽视频 + 人工/半自动标注；SSG 谓词做辅助；4 个任务 ×10 次即可起步。
- **资源**：1 人周 + 4 个调试槽 + 标注 2 人天。
- **步骤**：定义首败分类→标注 40 条→估计模式占比→选 2 个模式→接 SIGHTLINE。
- **风险**：样本少；标注主观；调试槽不可用 → 用离线回放/仿真兜底，但只作弱先验。

### 5.4 支撑 I2：视角流形 critic

- **动机**：ActiveAlign/WARP-VLA 证明视角 OOD 会把 VLA 打崩；需要一个“像不像演示”的分数。
- **差异**：不是全局外观相似度，而是目标相对腕部的几何/图像统计；任务/阶段条件化；可在图像空间落地。
- **可行性**：33k 演示足够；GMM/kNN 极轻；无需训练大模型。
- **资源**：离线 1–2 天；在线 <5ms。
- **步骤**：切段→提特征→拟合→held-out AUC→接 J。
- **风险**：流形多峰（不同抓法）→ 用 GMM 多分量；透明物体统计不稳 → 分桶回退。

### 5.5 支撑 I3：多物体路线规划

- **动机**：18 项任务有 2–5 个物体；顺序/手臂分配会影响碰撞、视角切换、时间。
- **差异**：不是纯 TAMP，而是用演示顺序做先验，用 SIGHTLINE 的 J 做边权，解一个带双臂约束的取放路由。
- **可行性**：物体数 ≤5，OR-Tools/2-opt 足够；碰撞/可达由路径层检查。
- **资源**：CPU；1 人周。
- **步骤**：建依赖图→演示顺序先验→路由→与 SIGHTLINE 共用路径评分。
- **风险**：路由收益被 VLA 执行误差吃掉 → 只在多物体任务启用。

### 5.6 实验 I4：Torso-Gimbal 重观察

- **动机**：腕部视角不能随便动；头戴相机在躯干上，可以用腰/躯干转头“看”，尽量保持手不动。
- **差异**：不是移动腕部（会改变 VLA 输入分布），而是用躯干自由度做“云台”；看完回到原状态。
- **可行性**：动作里有 `pivot`/`lower_body`；数据集有 waist 状态；IK 可保持 EE。
- **资源**：无新数据；调试槽验证。
- **步骤**：IK 保持 EE→优化躯干 yaw→可见性增益→回位。
- **风险**：躯干转动也可能 OOD；只作为“重观察”原语，不长时间改变状态。

## 6. 风险与合规（先立后破）

| 风险 | 概率 | 影响 | 缓解 | 停止条件 |
|---|---|---|---|---|
| H1 不成立：首败不在路径/遮挡 | 中 | 高 | 先用 FFA + 4 个调试槽 | <15% → 转抓取/插入 |
| 视角流形太窄，路径无解 | 中 | 中 | 多分量 GMM + 可见性回退 + 抬升绕行 | 无解率 >20% → 去掉流形项 |
| 腕部外参缺失 | 高 | 中 | 图像空间流形（质心/尺度/遮挡）为主；3D 只用头戴双目 | 标定误差 >2cm → 不用于精细插入 |
| 单模型审计：SAM2/FoundationPose 算不算第二个模型 | 中 | 高 | 默认用双目+平面+颜色/几何分割；学习型检测器逐个披露，必要时邮件确认 | 明确禁止 → 全经典感知 |

## 2. 评分与需求分析

### 2.1 成功率优先的数学

```text
排名 = mean_t P_t(成功)
P_t(成功) = P_t(首败 = 无)
```

设 `F_t ∈ {0, 1, ..., K}` 为一次 trial 的首次失败步骤（0=成功）。则：

```text
P_t(成功) = P_t(F_t = 0)
E[步骤分] = Σ_k w_k · P_t(第 k 步完成)
```

步骤分只用于成功率相同的情况。因此：

- 只提高失败 trial 的后段步骤分，不改变 `P_t(F_t=0)`，对排名几乎无用。
- 一次干预的价值 = 它把 `F_t` 从“非 0”变成“0”的概率 × 该任务权重。
- 如果干预只对某一类首败有效，应先估计该类首败的占比。

### 2.2 FFA 首败归因

**分类**（可扩展）：

```text
F1 目标/物体定位错（找错、跟丢）
F2 抓取失败（空抓、滑、夹偏）
F3 中段路径失败（碰撞、卡住、掉落、扫倒干扰物）
F4 视角/遮挡失败（目标看不见、视觉伺服丢目标）
F5 放置/插入失败（对不准、深度/力不够、弹跳）
F6 时序/步骤失败（跳步、假完成、顺序错）
F7 人扰恢复失败（物体被移走/步骤被撤销后不会重来）
F8 超时
```

**数据来源**：

1. 调试槽/计分跑的完整视频（官方 `runs`/`details` 后续可能给真实视频）。
2. 我们自己的 N 端口日志（obs、action、时间戳）；可离线重放。
3. SSG 谓词 + 夹爪/EE 事件做半自动预标注。
4. 人工抽检 20%，标“首败帧 + 模式 + 对象”。

**模型**：

```text
y_{t,a,i} ~ Bernoulli(p_{t,a})
logit(p_{t,a}) = α + β_a + u_t + γ_{m(t,a)}
u_t ~ N(0, σ_task²)
γ_m ~ N(0, σ_mode²)
```

- 先验弱信息；用 PyMC/Stan 或简单的分层 bootstrap。
- 对每个干预，估计 `Δ_m = P(成功 | 干预, 首败=m) - P(成功 | 基线, 首败=m)`。
- 选择 `argmax_m (占比_m × Δ_m × 覆盖任务数 / 成本)`。

**最小可行版**：4 个任务 ×10 次 = 40 条；人工标首败；按模式计数；不要一开始就上复杂模型。

### 2.3 铰链任务选择

不要选“最弱轴”，也不要选“最简单任务”。用：

```text
优先级 = (1 - p_t) × f_m × R_m / cost
```

- `p_t`：当前成功率（先用基线调试槽估计；没有就用任务难度/先验）。
- `f_m`：该首败模式被 SIGHTLINE 修好的概率（先验 0.3–0.5）。
- `R_m`：同一干预能覆盖的任务数（路径/视角模式覆盖多）。
- `cost`：调试槽/工程成本。

**候选**：

| 任务 | 为什么是铰链 | 首败假设 | 干预 |
|---|---|---|---|
| T27 StackBowls | 3 碗、堆叠、human_4 撤销 | F3/F4/F5 | 路径 + 视角 + SVL |
| T24 ConveyorSorting | 运动目标 + 人把物品放回 | F1/F3/F7 | 重定位 + 重规划 |
| T10 PlugCharger | 插排/插头插入 | F4/F5 | 视角 + 力控 |
| T19 ZipUp | 拉链、闭合终局 | F4/F5 | 视角 + 腕部伺服 |
| T13/T17/T02/T04/T20/T25 | 多物体、路径长 | F3/F6 | 路线 + 路径 |

### 2.4 统计功效

- 单任务 10 次：p=0.5 时 SE≈0.158；p=0.3 时 SE≈0.145。
- 32 任务平均（独立）：SE≈0.027；+5pp≈1.85σ；+8pp≈3σ。
- 同一模型在任务间正相关时，全局 SE 会更大；不要假设独立。
- 调试槽可以做配对重复（同一任务、同一初始条件、A/B），功效远高于跨任务平均。
- 结论：**主证据用调试槽配对；计分跑只做方向性验证。**

## 3. 头部方案分析：为什么侧翼打路径层

### 3.1 四类原型的强项/弱项

| 原型 | 强项 | 弱项 | 对 UniBot 的含义 |
|---|---|---|---|
| 3D/深度 VLA（MolmoAct2） | 空间 grounding、深度 token、快 | 深度粗（10×10）；无碰撞/路径；chunk 开环 | 语义够，几何不够；路径层是互补 |
| 通才 VLA（WALL/π0.5/GR00T） | 语义泛化、跨本体 | 视角敏感、遮挡、无显式几何 | 路径/视角层可模型无关地加 |
| 世界动作模型（DreamZero/GigaBrain） | 未来预测、新任务泛化 | 重、慢、幻觉、无安全保证 | 确定性几何层补物理盲区 |
| 混合推理（Spirit/DM0） | 可能更强的高层推理 | 公开细节少 | 暂不推断 |

### 3.2 共同瓶颈

1. **2D/2.5D 反应式策略**：输入是图像 + proprio，输出是 chunk；没有显式 free-space/碰撞/可达表示。
2. **开环 chunk**：chunk 内不重规划；遇到人扰/碰撞，可能继续执行错误动作。
3. **视角敏感**：腕部视角一变，策略 OOD；主动视觉直接前置会掉点。
4. **成功/失败不可验证**：模型不知道步骤是否真的完成；需要外部谓词/视觉校验。
5. **长程误差累积**：2–5 步任务里，每一步的小误差会累积；中段碰撞会不可逆。

### 3.3 侧翼策略

**不跟它们比“更大的模型/更多数据”，而是给任意一个开源 VLA 加一个“几何 + 视角”的测试时层。** 这有三个好处：

- 算力小：不需要预训练 6B/14B；用 WLA-1.0-Base 或 MolmoAct2 的公开权重即可。
- 归因清楚：路径层是确定性代码，消融容易；成功/失败可解释。
- 合规简单：唯一学习策略仍是那个 VLA；路径层/感知层披露即可（需确认感知基础模型是否算“多个模型”）。

## 4. SIGHTLINE 架构

### 4.1 总览

```text
Offline
  33k demos ──► 任务/相位切分 ──► 视角流形（GMM/kNN）
                └─► transit 路径库（目标/容器相对坐标）
                └─► 路径评分权重校准（demo vs 扰动）

Online (each get_action)
  obs ──► 场景图（双目深度/平面/掩码/6D/占据/变化）
      ──► SSG 相位（approach/grasp/transit/pre-place/insert/close）
      ──► 候选路径（演示 warp + cuRobo + 抬升绕行）
      ──► J 评分（碰撞 + 可见 + 流形 + 长度）
      ──► 选择/接管（最小干预）
      ──► chunk 执行（路径跟踪 + 视角锁定）
      ──► 触发重规划/重观察
```

### 4.2 离线：演示视觉流形（VMC）

**目标**：给定任务 `t`、相位 `p`，判断一个腕部视角 `ξ` 是否“像演示”。

**特征**（图像空间优先，避免腕部外参依赖）：

```text
ξ = [ u, v, log s, θ, o, Δu, Δv, Δlog s ]
u,v        目标/容器在腕部图像的质心（归一化）
s = sqrt(mask_area) / image_diag
θ          目标主轴在图像平面的角度（可选）
o          遮挡率（目标 mask 被夹爪/容器/其他物体遮挡的比例）
Δ          相对上一帧的变化（运动一致性）
```

若手眼标定可用，再加：

```text
ξ_3d = [ R_obj^T (p_cam - p_obj),  rot(R_obj^T R_cam), log s ]
```

**拟合**：

- 每任务/相位一个 GMM（K=4–8），或用 kNN + Mahalanobis。
- 80/20 划分；报告 held-out NLL、OOD 检测 AUC。
- 对多峰（不同抓法/不同容器）用 GMM 多分量；不要把多峰压成单高斯。

**用途**：

```text
NLL_view(ξ) = -log Σ_k π_k N(ξ; μ_k, Σ_k)
```

- 训练时不需要；只在推理时给路径评分。
- 透明/反光物体：mask/质心不稳 → 降低该项权重，回退到可见性 + 碰撞。

### 4.3 在线：场景图

**输入**：4 路 RGB、关节/EE、lower_body、language。

**步骤**：

1. **深度**：头戴双目校正后做 SGBM/FoundationStereo；转 base/torso 系。
2. **平面**：RANSAC 拟合桌面；法向/高度。
3. **掩码**：SAM2/GroundingDINO（可选）或经典颜色/几何；输出目标/容器/干扰物。
4. **6D 位姿**：已知物体用 FoundationPose/ICP；未见物体用支撑面 + 包围盒 + 主轴。
5. **占据**：1cm 体素/TSDF；机器人 URDF 自碰撞；被持物体用 mask/包围盒膨胀。
6. **变化检测**：与上一帧/上一 chunk 比较物体位姿；超过阈值 → 人扰/移动 → 重规划。
7. **可见性**：从候选腕部位姿向目标/容器采样射线；算投影面积、遮挡率、是否在视场内。

**输出**：`scene = {objects, containers, obstacles, occupancy, robot, payload, table_plane}`。

### 4.4 路径候选

**A. 演示路径检索（给人味）**

- 对每条演示，按夹爪闭合/EE 速度/SSG 相位切出 `transit` 段：从“抓稳”到“pre-place”。
- 存到目标/容器相对坐标：`T_obj^{-1} T_ee(t)`。
- 线上：检测当前目标/容器位姿，取 K 条最相似（起点/终点相对位移 + 目标尺寸）的路径，做相似变换/DTW warp。
- 检查 IK/碰撞；不通过就丢弃。

**B. 几何路径（给安全）**

- cuRobo/BiRRT*：从当前 EE 到 pre-place；采样 8–12 个末端的朝向/进入方向。
- 碰撞体：机器人 + 被持物体 swept volume；障碍膨胀 1–2cm。
- 代价：路径长度 + 关节加速度 + 与障碍的最小距离。

**C. 抬升绕行（给兜底）**

- `z_safe = max(障碍高度) + 5cm`；先抬到安全高度，平移到目标上方，再下降。
- 对高堆叠/容器壁可能不适用；作为 fallback。

**D. 双臂变体（可选）**

- 另一只手空闲时，先扶住容器/移开干扰物，再走主路径。
- 需要双臂碰撞检查；只在 T09/T18/T23/T29/T30/T31 等双手任务启用。

**候选数**：总计 ≤16；检索 6 + 几何 8 + 抬升 1 + 双臂 1。

### 4.5 评分函数

```text
J(τ) = Σ_t [ λ_c C_col(q_t, payload, scene)
           + λ_v (1 - V_t)
           + λ_m NLL_view(ξ_t)
           + λ_l ||p_{t+1} - p_t||
           + λ_a ||q_{t+1} - 2q_t + q_{t-1}|| ]
       + λ_T T(τ)
```

**碰撞风险**：

```text
C_col = Σ_j max(0, d_safe - d_j)^2 · r_j
```

- `d_j`：机器人/被持物体到障碍 `j` 的有符号距离。
- `r_j`：语义风险（玻璃/易倒/目标容器高；软物/纸盒低）。
- 用 CaSCo/IMPACT 的思想：不是所有接触都一样；但在本赛里，**碰到干扰物通常不可逆**，所以默认 `r_j` 高，只有“软/低风险”才允许轻触。

**可见性**：

```text
V = clip( A_mask · (1 - O) / A_ref, 0, 1 )
```

- `A_mask`：目标/容器在腕部图像的投影面积。
- `O`：遮挡率（自遮挡 + 场景遮挡 + 被持物体遮挡）。
- `A_ref`：演示中该相位的典型面积（中位数）。
- 对插入/拉链任务，`V` 权重要高；对中段搬运，`V` 权重中等。

**流形 NLL**：见 §4.2。

**权重初值**（离线校准）：

| 权重 | 初值 | 说明 |
|---|---:|---|
| λ_c | 1.0 | 碰撞优先 |
| λ_v | 0.5 | 可见性 |
| λ_m | 0.3 | 流形；先小后大 |
| λ_l | 0.05 | 长度 |
| λ_a | 0.02 | 平滑 |
| λ_T | 0.01 | 时间 |

校准方法：取 100 条 held-out 演示的 transit 路径作为正例；对每条做 5 种扰动（平移、加障碍、改朝向、缩短、随机）作为负例；网格搜索/逻辑回归调权重，使正例 J 低于负例（AUC>0.8）。**这不是训练策略，只是校准一个评分器。**

### 4.6 执行：最小干预

**原则**：能不改 VLA 就不改；只在 VLA 的隐含路径明显差于规划路径时接管。

```python
def get_action(obs):
    scene = update_scene(obs)
    phase = ssg.phase(obs.language, obs)
    goal  = pgl.opt_goal(scene, phase)          # 终点仍由 PGL/OPT 给

    if phase in ("approach", "transit", "pre_place"):
        if state.path is None or scene_changed(scene) or not valid(state.path, scene):
            cands = retrieve_paths(...) + sample_paths(...) + lift_over(...)
            state.path = min(cands, key=lambda p: J(p, scene, phase))
        vla_chunk = vla.act(obs)
        if path_cost(vla_chunk, state.path, scene) <= state.path_cost + δ:
            return vla_chunk                     # VLA 在轨道上，放行
        return track(state.path, horizon=chunk_size)  # 最小接管
    else:
        return vla.act(obs)                      # 抓取/插入/闭合交给 VLA + SVL
```

**路径跟踪**：

- 把路径转成 30Hz 的 EE 路点；用阻抗/位置控制跟踪。
- 每个 chunk 结束重新评估：若 VLA 已回到路径附近，交还 VLA。
- 接管时保留夹爪/腕部朝向，避免改变接触状态。

**视角锁定（view lock）**：

- 在 approach/pre-place 段，用腕部图像的目标质心/尺度做 IBVS 小修正：
  ```text
  Δu = u_target - u_demo_median
  Δv = v_target - v_demo_median
  Δlog s = log s_target - log s_demo_median
  ```
- 只调腕部姿态/小范围位置，不改变大路径；避免把 VLA 推出分布。

**chunk 大小**：

- 假设评估器 30Hz：chunk=8 → 0.27s 开环；可接受。
- 若评估器 10Hz：chunk=8 → 0.8s；建议 chunk=4。
- 延迟预算：感知 30ms + 规划 50ms + VLA 150–250ms → p99 <300ms；若超标，降候选数/感知频率。

### 4.7 重观察 / 恢复

**触发**：

```text
scene_changed > θ_scene
V < V_min (e.g., 0.15)
NLL_view > τ_m (e.g., 95th percentile of demos)
human disturbance detected
```

**重观察原语**：

1. **腕部微移**：抬腕 2–5cm / 侧移 2cm，保持目标在视场；看完回位。
2. **Torso-Gimbal**：用腰/躯干 yaw 改变头戴相机视角，IK 保持 EE；适合目标被手臂/夹爪挡住。
3. **换手**：另一只手空闲时，用它拨开/扶住遮挡物；只在安全时。
4. **退回安全位**：抬到 `z_safe`，重新看桌面，再规划。

**人扰恢复**：

- 检测到物体位姿跳变 → 重建场景图 → 重新定位目标/容器 → 重规划。
- 如果当前步被撤销（如 T27 第二个碗被拿走），SSG 回退一步，重做该步；不要从头开始。
- 预算：普通任务 ≤2 次；长程 ≤1 次；总时长守卫 180s。

### 4.8 伪代码（完整）

```python
class SIGHTLINE:
    def __init__(self, vla, ssg, pgl, svl, vm, planner):
        self.vla, self.ssg, self.pgl, self.svl = vla, ssg, pgl, svl
        self.vm, self.planner = vm, planner
        self.path = None
        self.path_cost = None
        self.last_scene = None

    def reset(self):
        self.path = None
        self.path_cost = None
        self.last_scene = None

    def act(self, obs):
        scene = self.build_scene(obs)
        phase = self.ssg.phase(obs["observation.language"], obs, scene)
        goal = self.pgl.goal(scene, phase)

        if phase in ("transit", "pre_place"):
            if (self.path is None
                or self.scene_changed(scene, self.last_scene)
                or not self.planner.valid(self.path, scene)):
                cands = []
                cands += self.retrieve_paths(scene, goal, k=6)
                cands += self.planner.sample(scene, goal, k=8)
                cands += [self.planner.lift_over(scene, goal)]
                scored = [(self.J(p, scene, phase), p) for p in cands]
                self.path_cost, self.path = min(scored, key=lambda x: x[0])
                self.last_scene = scene

            cand = self.vla.act(obs)
            if self.track_cost(cand, self.path, scene) <= self.path_cost + 0.1:
                return cand
            return self.track(self.path, scene, horizon=self.chunk)
        else:
            return self.vla.act(obs)

    def J(self, path, scene, phase):
        col = self.collision_risk(path, scene)
        vis = self.visibility(path, scene, phase)
        nll = self.view_nll(path, scene, phase)
        length = self.length(path)
        return 1.0*col + 0.5*(1-vis) + 0.3*nll + 0.05*length

    def visibility(self, path, scene, phase):
        vals = []
        for q in path:
            T_w = self.fk_wrist(q)
            vals.append(self.render_visibility(T_w, scene.target, scene.robot))
        return min(vals)  # 保守：最差可见性

    def view_nll(self, path, scene, phase):
        vals = []
        for q in path:
            xi = self.view_features(self.fk_wrist(q), scene)
            vals.append(self.vm.nll(xi, phase))
        return sum(vals) / len(vals)

    def track(self, path, scene, horizon):
        return self.planner.to_ee_chunk(path, scene, horizon)
```

## 5. 数据与工程

### 5.1 数据管线

| 步骤 | 输入 | 输出 | 工具 | 备注 |
|---|---|---|---|---|
| 1. 相位切分 | 33k 演示 | 每段 `approach/grasp/transit/pre_place/insert/close` | 夹爪事件 + EE 速度 + SSG 文本 | 先抽 300 条/任务，不跑全量 |
| 2. 视角特征 | 四路视频 + mask | `ξ` 序列 | SAM2/经典分割 + 目标跟踪 | 图像空间优先 |
| 3. 流形拟合 | `ξ` | GMM/kNN | scikit-learn | 每任务/相位一个 |
| 4. 路径库 | EE 位姿 | 目标/容器相对路点 | numpy/DTW | 只存 transit |
| 5. 路径评分校准 | 正/负路径 | λ 权重 | 网格/逻辑回归 | held-out 100 条 |
| 6. 场景图 | 双目/位姿 | 占据/物体/容器 | Open3D/FoundationPose | 1cm 体素 |
| 7. 仿真 | Isaac Lab/MuJoCo | 6 任务 ×5 布局 | 官方 URDF | 只做相对比较 |

**规模**：每任务 300 条 ×32 = 9,600 条用于建流形/路径库；其余做 held-out。显存/存储可控。

### 5.2 标定

- **头戴双目**：`camera_params` 已给内参/畸变/校正；用 `state_d435` 得相机位姿；转 base/torso。
- **腕部外参**：数据集未显式给。优先级：
  1. **图像空间流形**（不需要外参）：目标质心/尺度/遮挡/朝向。
  2. URDF + 安装件近似：若 G1/Dex1 的腕部相机安装已知。
  3. 手眼标定：打印棋盘格，在调试槽前做一次；或用已知桌面标记做 PnP。
- **验收**：头戴重投影 <5px；桌面平面 <5mm；EE 回放 <2cm；腕部外参若用，重投影 <10px。

### 5.3 感知

- **深度**：SGBM 基线；可选 FoundationStereo（若许可/算力允许）。透明物体用 RGB mask + 支撑面，不依赖深度。
- **分割**：SAM2/GroundingDINO 可选；若“单模型”审计不允许，改用：
  - 桌面平面 + 颜色聚类 + 连通域；
  - 目标/容器用语言 grounding 的 2D 框（可由 VLA 的 attention/检测头给）。
- **6D 位姿**：已知物体 FoundationPose/ICP；未知物体用主轴 + 支撑面 + 抓取点。
- **人扰**：物体位姿/掩码面积突变；手部检测（肤色/运动）可选。

### 5.4 路径规划

- **cuRobo**：GPU 并行 IK/碰撞/轨迹优化；适合 7-DOF 双臂；需 G1 URDF + Dex1 碰撞体。
- **BiRRT***：CPU fallback；高维/窄通道。
- **碰撞体**：机器人 links + 被持物体（mask/包围盒/已知 mesh）；障碍膨胀 1–2cm。
- **时间**：16 候选 × 每条 50 点 × 碰撞检查；目标 <50ms（GPU）/ <200ms（CPU）。

### 5.5 实时性预算

| 模块 | 频率 | 延迟目标 | 备注 |
|---|---:|---:|---|
| 场景图 | 5–10Hz | 30ms | 只在 chunk 边界更新 |
| 路径规划 | 2Hz/段 | 50ms | 缓存；场景变化才重跑 |
| 视角流形 | 每候选 | <5ms | GMM 闭式 |
| VLA | 每 chunk | 150–250ms | 6B/4B；量化/蒸馏可选 |
| 总 `get_action` | 每 chunk | p99 <300ms | 官方会记录延迟 |

**降级**：候选 ≤8；场景图 5Hz；流形 kNN 而非 GMM；路径只做几何不检索。

### 5.6 单模型合规

- **唯一策略模型**：一个 VLA checkpoint（WLA-1.0-Base 或 MolmoAct2）。
- **确定性组件**：场景图、路径规划、评分、SVL、SSG。均非“模型”。
- **可选基础模型**：SAM2/FoundationPose/FoundationStereo。若官方认定“多模型”，则：
  - 改用经典分割/深度；
  - 或把这些模型视为“感知预处理”并在模型卡披露，邮件确认。
- **模型卡**：写清所有组件、数据来源、是否学习、是否外部权重。
- **不碰**：不引入第二个策略、不做模型集成、不做每任务 LoRA。

### 6.5 计分跑

- 最多 2 次：W7 中期、W8 终期；若只允许 1 次，放 W8。
- 提交前 4h soak：N 端口并发、状态隔离、健康检查、延迟 p99、token 双处校验。
- 计分跑后做 FFA：从视频/日志标首败；更新下一轮预算。
- 不在计分跑中间改代码；版本冻结。

### 6.6 指标与统计

**主**：

```text
Success = mean_t (1/10) Σ_i 1(trial t,i 成功)
```

**次**：

- 首败模式分布（F1–F8）。
- 碰撞率（每 trial 与障碍的接触次数/位移）。
- 目标可见率（关键相位的最小/平均 V）。
- 视角流形 NLL（关键相位的均值/95 分位）。
- p50/p99 `get_action` 延迟；整局时长；超时率。
- 恢复率（人扰后继续完成任务的比例）。

**统计**：

- 分层 logistic：`logit(p_t) = α + β·I + u_t`，`u_t ~ N(0, σ²)`。
- 配对调试槽：McNemar / 配对 bootstrap。
- 预注册：任务、假设、主指标；不看到结果后换指标。
- 报告 95% CI，不只报点估计。

### 7.2 I0 FFA 首败归因（新增，押注）

- **动机**：排名只看成功率；第 7 轮把终局当首败，可能押错；榜单是占位，不能做归因。
- **差异**：不按步骤权重分配，按“第一次失败的模式”分配；用分层贝叶斯处理 10 次/task 的噪声；用调试槽做配对。
- **可行性**：调试槽视频 + SSG 谓词 + 人工标注；4 任务 ×10 次即可起步。
- **资源**：1 人周；4 个调试槽；2 人天标注；无需新数据。
- **步骤**：定义 F1–F8 → 标 40 条 → 估计模式占比 → 选 2 个模式 → 接 SIGHTLINE → 计分跑后复标。
- **风险**：样本少/主观/槽稀缺 → 用离线回放/仿真兜底，但只作弱先验；预注册分类。
- **状态**：押注（与 I1 并列）。

### 7.3 I1 SIGHTLINE（新增，押注）

- **动机**：中段是 VLA 最没有几何约束的一段；干扰物/位置/人扰三轴同时打这里；碰撞/遮挡不可逆。
- **差异**：不是安全滤波（只避碰），不是主动视觉（只找可见位姿），不是轨迹检索（只 warp），而是把**碰撞 + 可见性 + 演示视角流形**放进同一路径评分；冻结 VLA。
- **可行性**：双目 3D、URDF、cuRobo、SAM2/经典分割现成；腕部流形可退化为图像统计；chunk 可调小。
- **资源**：1×A100 实时；8×H100 3–5 天离线；CPU/GPU 路径采样；无新数据。
- **步骤**：FFA → 流形 → 场景图 → 候选 → 评分 → 执行 → 调试槽。
- **风险**：流形太窄/外参缺失/延迟/单模型审计/H1 不成立 → 分桶回退、图像空间、降候选、经典感知、转抓取。
- **状态**：押注（主技术注）。

### 7.4 I2 VMC 视角流形（新增，支撑）

- **动机**：ActiveAlign/WARP-VLA 证明视角 OOD 会把 VLA 打崩；需要一个“像不像演示”的分数。
- **差异**：不是全局外观相似度，而是目标相对腕部的几何/图像统计；任务/相位条件化；图像空间可落地。
- **可行性**：33k 演示足够；GMM/kNN 极轻；无需训练大模型。
- **资源**：离线 1–2 天；在线 <5ms。
- **步骤**：切段 → 提特征 → 拟合 → held-out AUC → 接 J。
- **风险**：多峰/透明 → GMM 多分量、分桶回退。
- **状态**：支撑（I1 的必要组件）。

### 7.5 I3 Route 多物体路线（新增，支撑）

- **动机**：18 项任务有 2–5 个物体；顺序/手臂分配影响碰撞、视角切换、时间。
- **差异**：不是纯 TAMP；用演示顺序做先验，用 SIGHTLINE 的 J 做边权，解带双臂约束的取放路由。
- **可行性**：物体 ≤5；OR-Tools/2-opt；路径层检查碰撞/可达。
- **资源**：CPU；1 人周。
- **步骤**：依赖图 → 演示顺序先验 → 路由 → 与 SIGHTLINE 共用评分。
- **风险**：VLA 执行误差吃掉路由收益 → 只在多物体任务启用。
- **状态**：支撑（中优先）。

### 7.6 I4 Torso-Gimbal 重观察（新增，实验）

- **动机**：腕部视角不能随便动；头戴相机在躯干上，可以用腰/躯干转头“看”，尽量保持手不动。
- **差异**：不是移动腕部（会改变 VLA 输入分布），而是用躯干自由度做“云台”；看完回位。
- **可行性**：动作有 `pivot`/`lower_body`；数据集有 waist 状态；IK 可保持 EE。
- **资源**：无新数据；调试槽验证。
- **步骤**：IK 保持 EE → 优化躯干 yaw → 可见性增益 → 回位。
- **风险**：躯干转动也可能 OOD → 只作为短时重观察原语。
- **状态**：实验（低优先，等 I1 稳定）。
