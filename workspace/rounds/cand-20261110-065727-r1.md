# 第 42 轮（新循环第 2 轮） · 行为树 × 奖励设计：用「可恢复结构 + 被约束的奖励」把安全-可用张力写成可组合设计（四层架构 v7）

> 承接第 41 轮 v18（CAR 运行时证书自动机 × LCS 轻量认证 × CMC 看门狗）。第 41 轮自陈最大风险是「可用性崩塌」：证书一旦成为转移守卫，保守界会把机器人长期锁进 Degraded/SafeStop，「可认证」变成「可瘫痪」。本轮灵感词「行为树」「奖励设计」正好各补一刀：**行为树**把平坦自动机的恢复边升级为层级化 Fallback 结构，使「回到 Nominal」成为可组合、可验证的结构性性质；**奖励设计**回答另一个更尖锐的问题——能否用奖励诱导策略主动远离边界、把保守界在实践中收紧。答案一半是肯定的（势函数塑形加速、奖励机表达非马尔可夫任务），一半是必须说清的否定（塑形在无约束 MDP 中不改变最优策略，安全只能来自约束/屏蔽，不能来自奖励）。核心主张：**行为树是奖励机的控制器对偶，而证书必须同时约束二者。**

## 0. 直觉与动机

**灵感 1（行为树 → 恢复是结构，不是补丁）**
第 41 轮把运行期压成 5 态平坦自动机，恢复只有一条 SafeStop→Escalate 边。它能证明安全，却答不了「怎么回来」：从 Degraded 回 Nominal 需要满足一长串合取条件，任何一条不满足就卡住，可用性因此崩塌。行为树的直觉是：把「先试 Nominal，不行退 Watch，再不行退 Degraded，最后 SafeStop」写成 **Fallback（选择）树**。Fallback 的语义天然是「按优先级尝试、第一个非失败分支胜出」，它把恢复从「一条边」变成「一棵可递归重试的子树」。于是恢复不必在自动机里逐条枚举，而由结构保证：只要某分支的前置条件与证书重新成立，下一次 tick 就自动重新选到它。**瘫痪不再是安全策略的副作用，而是树缺少可恢复分支时才会暴露的结构缺陷**，可被结构检查直接发现。

行为树还自带 `Running` 状态。第 41 轮的 anytime 证书需要知道「这一拍够不够做决定」；在树里，一个 Running 节点其实就在说「该子树仍在执行、其部分证书仍然有效」。这给 anytime 一个天然的运行时载体：**证书不挂在平坦态上，而挂在正在 Running 的子树契约上**。子树的组合（Sequence 的前后置、Fallback 的析取、Parallel 的合取）正好对应证书的合成规则。它还把 IP-47 的乘积自动机从「状态笛卡尔积」升级为「结构化组合子」，状态爆炸被层级与短路大幅缓解。

最后必须继承旧轮 SURE-BT 的硬约束：UniBot 的 action chunk 是开环执行的，**BT 只能在 chunk 边界 tick**（T_a=8、30Hz ⟹ 决策周期 267ms）。所以本轮的行为树是**编译期确定性的分块同步树**，不是让 LLM 在线生成树；「人扰反应盲区」要靠每个 chunk 结束在可验证、可恢复的端点来吸收。

**灵感 2（奖励设计 → 一半加速器，一半边界条件）**
奖励设计最容易犯的错，是以为「把安全写进奖励」就能安全。保守界之所以可恶，是因为它把大量「其实安全」的状态误判为危险，导致可用性下降。能否用奖励让策略主动抬高边际，使保守界在实践中变紧？可以，但必须分清三件事：
1. **势函数塑形只能加速，不能改最优策略**：把证书边际 m(x) 变成势 Φ(x)，用 F=γΦ(s′)−Φ(s) 做塑形（Ng–Harada–Russell），在无约束 MDP 中最优策略不变。它能让策略更快学会「贴着高边际走」，却绝不可能让一个本来会违规的最优策略变安全。**安全必须由约束/屏蔽提供，奖励只负责在可行域内提升样本效率与收敛边际。**
2. **奖励机负责非马尔可夫**：很多任务不是「到 A」，而是「先拿钥匙、再开门、过程中不能碰火」，状态奖励表达不了，必须用带记忆的奖励机。而奖励机与行为树结构对偶：都是有限记忆自动机，都能层级组合。于是可用**同一个规格对象**同时生成控制器（树）、学习信号（奖励）与监控器（证书）。
3. **奖励会被钻空子（Goodhart）**：奖励是代理，证书边际也是代理（估计出来的界），策略会找到代理与真值之间的缝。所以奖励必须服从**字典序安全**：安全是硬约束，奖励只在可行域内比较；屏蔽只能挡「已知」不安全动作，真正危险的是**守卫集不完备**——这是本轮要正面承认并实验的攻击面。

**耦合**：行为树给奖励设计提供「动作的语义单元」（叶子技能 + 前置/后置契约），奖励机给行为树提供「任务的时间语义」（非马尔可夫目标），证书同时给两者当守卫与势函数。三者不是拼装，而是同一个「证书奖励机」的三次编译；第 41 轮的 CMC 看门狗正好复用为第三个产物。

## 1. 形式化定义

**定义 32（证书契约行为树 CBT）**：T=(N,type,child,C)，N 为有限节点，type∈{Sequence,Fallback,Parallel_k,Decorator,Action,Condition,SafeStop}，child 给出有序子节点；每节点 n 带契约 C(n)=(Pre_n,Post_n,Inv_n,θ_n,Cert_n)，状态 τ(n)∈{S,F,R}。合成规则：Condition/Action 叶子在 Pre∧Cert 成立时返回 S 并承诺 Post，Pre 失败返回 F，证书不可判定返回 R（保守、不推进）；Sequence 返回最后一个成功子节点的 Post，任一 F 则整段 F 且不承诺 Post；Fallback 返回第一个非 F 分支的状态，证书取被选中分支的证书（分支间析取 ⋁）；Parallel_k 的证书是所需 k 个分支证书的合取 ⋀。**可靠性**：根返回 S/R 时 Inv_root 在 (1−δ) 置信下成立；根返回 S 时 Post_root 成立。

**定义 33（证书守卫奖励机 CRM）**：RM=(U,u₀,AP,δ,L,ρ,G)，U 为有限记忆态，AP 含 CAHA 守卫文字与状态谓词，δ:U×2^AP→U，ρ:U×U×2^AP⇀R 为偏函数，G 为证书守卫。**安全对齐**：ρ(u,u′,σ) 仅在 G 成立时有定义；¬G 时该转移被屏蔽（奖励 ⊥）。目标为**字典序**：先要求 Pr[进入 ¬G]≤δ，再在可行策略集内最大化期望回报。由定义，奖励永远无法补偿一次守卫违反——这把「奖励设计不能替代证书」写进了类型系统。

**定义 34（证书塑造奖励 CSR）**：势函数 Φ(x)=ψ(m(x)−θ)，ψ 单调递增、Lipschitz，例如 ψ(z)=clip(z/Δ,0,1)。塑形项 F(s,s′)=γΦ(s′)−Φ(s)，总奖励 r_tot=r_task+λF（仅在可行域内累加）。**命题（政策不变性）**：在无约束 MDP 中 F 不改变最优策略集（Ng 等 1999）；**推论**：任何「调大 λ 让策略变安全」的设想都是错的，安全必须来自定义 33 的屏蔽与约束。Φ 的正确用途是加速收敛、提高收敛后的边际 m，从而延长 T_hold、降低重认证频率。

**定义 35（反瘫痪活性）**：称状态在 t 处**可恢复**，若从根经 Fallback 存在叶子 ℓ 使 Pre_ℓ 成立且 Cert_ℓ 在 (1−δ) 下有效。若存在 t_k→∞ 使可恢复在 [t_k,t_k+τ_min] 内持续，且树无永久失败闩锁，则公平调度下 □◇Nominal，且恢复时间 ≤ depth(T)·τ_tick+τ_min。**这是结构性性质**：不依赖策略学到什么，只依赖树里存在可恢复分支——这就是对第 41 轮「可用性崩塌」的直接回答。

**定义 36（Goodhart 间隙与守卫覆盖）**：设 Π_feas 为零守卫违反的策略集。奖励劫持度 H(π)=E_π[Σr]−max_{π′∈Π_feas}E_{π′}[Σr] 在违规轨迹上的投影；硬屏蔽下可证 H≡0（若屏蔽只删真违规动作，则可行最优不变）。但屏蔽只能挡**已知守卫**：定义守卫覆盖缺口 = P(存在未建模危险 | 分布外)。**结论**：形式化保证「已知安全」，不保证「未知安全」，后者只能靠 OOD 检测与在线证书重估。

**定义 37（证书奖励机编译与三产物等价）**：给定 CRM 规格 S，编译映射 κ(S)=(T_S,r_S,M_S)，分别为 CBT 控制器、塑形+屏蔽奖励、流式监控器。称 κ **语义正确**，若对任意采样轨迹 ξ，T_S 在 ξ 上不返回 F（或返回 SafeStop）当且仅当 M_S 不 trip，且 r_S 的屏蔽掩码与 ξ 的守卫违反一一对应。三产物不一致即编译失败，不允许「控制器安全但奖励鼓励违规」的分裂。

## 2. 三大产出设计

### 2.1 IP-54 CERTIFIED-BEHAVIOR-TREE（CBT，证书契约行为树）
1. 节点库：Sequence/Fallback/Parallel_k/Retry/Timeout/Inverter + Action/Condition/SafeStop；每个 Action 绑定 IP-52 的 anytime 证书与 IP-39 的 margin。
2. 契约合成器：自底向上推导 (Pre,Post,Inv,Cert)；Sequence 做前后置串接，Fallback 做析取，Parallel 做合取；冲突时插入 Condition 守卫或安全叶子。
3. 恢复性检查：自动检测每个 Fallback 是否覆盖 SafeStop 之外的可恢复路径，给出「可恢复分支缺失」反例。
4. 分块同步：树只在 chunk 边界 tick，每个 chunk 必须结束在满足 Post 的端点；树内 Retry 的预算计入下一 chunk 的前置。
5. 展平与验证：把带记忆 CBT 展平成有限状态机，与 IP-51 CAHA 做 bisimulation 检查，复用 E73 的模型检验。
6. 组合：子树即技能（接 IP-47），组合子是 Sequence/Fallback/Parallel，精化关系为「契约蕴含 + 展平后 simulation」。

### 2.2 IP-55 CERTIFIED-REWARD-MACHINE（CRM，证书守卫奖励机）
1. 规格语言：用原子命题（守卫、语义事件、几何谓词）写非马尔可夫任务；每个转移带证书守卫 G 与奖励 ρ。
2. 安全对齐编译：¬G 的转移在屏蔽层被删除，奖励只能在 G 内发放，输出「奖励不可补偿安全」的类型检查。
3. 塑形自动生成：从 IP-52 边际自动构造 Φ，保证 Lipschitz 与有界；λ 作为课程变量由 IP-50 调度。
4. 安全探索：把 Φ 的增量作为探索 bonus，只在边际上升方向给奖励，实现「贴着高边际探索」。
5. 奖励审计：离线枚举高奖励轨迹，检查守卫违反率，输出 H 与覆盖缺口报告。

### 2.3 IP-56 REWARD-CONTROL-COMPILER（RCC，奖励-控制编译器）
1. 单一规格 CRM 编译出三件套：CBT 控制器、塑形奖励信号、CMC 流式监控器（复用 IP-53）。
2. 语义一致性：三段产物在采样轨迹上的接受语言相同（定义 37 的 trace 等价），不一致即编译报错。
3. 监控器从 CRM 的 G 与 CBT 的 Inv 双源生成、交叉校验，单边可靠性沿用 IP-53。
4. 热更新：CRM 变更时三件套原子替换，旧轨迹按版本号归档。

## 4. 实验设计（E79–E84 硬门槛）

| 实验 | 指标 | 门槛 |
|---|---|---|
| E79 CBT 契约可靠性 | 契约合成验证通过率；反例数；展平 bisimulation | 100%；0；等价 |
| E80 反瘫痪活性 | 卡在 Degraded 的最长时长；恢复成功率；Nominal 占比 | <2s；≥99%；≥80%（v18 为 70%） |

## 5. 本轮最大风险

**一句话**：最大风险不是「奖励太弱学不会」，而是**对齐幻觉**——行为树保证「有路可回」、奖励塑形提升「实践边际」、屏蔽挡住「已知违规」，三者都很漂亮，却都建立在「守卫集完备 + 边际估计可信」这个未证前提上；一旦守卫漏掉一类危险或边际在 OOD 处系统性偏乐观，结构活性会让人误以为系统既安全又可用，实际上只是把失败推迟到分布外。

| τ(n) | 节点状态 | S 成功 / F 失败 / R 运行中 |
| C(n) | 节点契约 | 可靠性：根 S/R ⇒ Inv 成立；根 S ⇒ Post 成立 |
| RM=(U,u₀,AP,δ,L,ρ,G) | 证书守卫奖励机 | ρ 为偏函数，仅在 G 内定义；¬G ⇒ 屏蔽 |
| G | 证书守卫 | 由 CAHA 守卫与 IP-52 保守下界构成 |
| Φ(x)=ψ(m(x)−θ) | 塑形势函数 | 单调递增、Lipschitz；ψ(z)=clip(z/Δ,0,1) |
| F(s,s′)=γΦ(s′)−Φ(s) | 塑形项 | 无约束 MDP 中政策不变 |
| λ | 塑形权重 | 由 IP-50 课程调度；过大只影响探索，不改变可行性 |
| H(π) | 奖励劫持度 | 违规轨迹上 E[Σr] 超出可行最优的投影 |
| κ(S)=(T_S,r_S,M_S) | RCC 编译 | 三产物 trace 等价；不一致即编译失败 |
| τ_tick | 分块 tick 周期 | T_a/f_ctrl，UniBot 典型 8/30Hz≈267ms |

## 2. 关键算法（伪代码）

### 2.1 IP-54 CBT：契约合成 + 分块 tick
```
def synthesize_contract(node):
    if is_leaf(node):
        return node.C                         # Pre/Post/Inv/Cert 由 IP-52 给出
    if node.type == Sequence:
        Pre  = node.child[0].Pre
        Post = node.child[-1].Post
        Inv  = And(c.Inv for c in node.child) \
               & And(implies(child[i].Post, child[i+1].Pre))
    elif node.type == Fallback:
        Pre  = Or(c.Pre for c in node.child)   # 任一分支可用即可
        Post = Or(c.Post for c in node.child)
        Inv  = Or(c.Inv  for c in node.child)
    elif node.type == Parallel_k:
        Inv  = And(c.Inv for c in node.child)
        Post = And(c.Post for c in selected(node, k))
    assert subset(Pre, Inv)
    assert covers_recovery(node), missing_recovery_witness(node)   # 结构反例
    return Contract(Pre, Post, Inv, Cert=compose_cert(node))

def tick(node, x):                              # 只在 chunk 边界调用
    if node.type == Fallback:
        for c in node.child:                    # 结构性恢复：每拍重新尝试高优先分支
            s = tick(c, x)
            if s != F: return s
        return F
    if node.type == Sequence:
        for c in node.child:
            s = tick(c, x)
            if s != S: return s                 # R/F 都短路，保证不承诺 Post
        return S
    return run_leaf(node, x)                    # Pre∧Cert→S；不可判定→R（保守）
```
> `run_leaf` 返回 R 是关键：**证书不确定时不允许推进**，但也不许声明失败，否则 Fallback 会误降级——这正好把「保守」限制在时间维度而不是安全性维度。

### 2.2 IP-54 反瘫痪活性检查（定义 35 的可执行版）
```
def check_liveness(T):
    for fallback in find_all(T, Fallback):
        # 每个 SafeStop 之外，是否至少有一个可恢复叶子？
        recoverable = [l for l in leaves(fallback)
                       if l is not SafeStop and satisfiable(l.Pre & l.Cert)]
        if not recoverable:
            return Counterexample(node=fallback, why="no recovery branch")
    # 有界恢复时间：depth * tau_tick + tau_min
    return Proof(bound=depth(T)*tau_tick + tau_min)
```

### 2.3 IP-55 CRM：屏蔽 + 塑形 + 审计
```
def step_rm(rm, u, x, a):
    G = guard(rm, u, x)                        # 证书保守下界
    if not G.satisfied:
        return MASK                            # 奖励不可补偿安全（定义 33）
    u2 = rm.delta(u, props(x, a))
    r_task = rm.rho(u, u2, props(x, a))        # rho 仅在 G 内有定义
    Phi = lambda z: clip((margin(z)-theta)/Delta, 0, 1)
    r_shape = gamma*Phi(next_state(x,a)) - Phi(x)
    return u2, r_task + lam*r_shape            # 政策不变：只加速（定义 34）

def audit(rm, policy, N):
    viol = count_violations(rollout(policy, rm, N))
    H = proxy_return(policy) - feasible_optimum(rm)
    return Report(viol=viol, H=H, coverage_gap=estimate_ood_gap(rm))
```

### 2.4 IP-56 RCC：一次规格，三次编译 + trace 等价
```
def compile(rmspec):
    cbt     = rm_to_bt(rmspec)                 # 状态→子树；转移→Condition+Action
    reward  = lambda s,a,s2: shade(rmspec, s,a,s2, Phi=cbt.margin)
    monitor = compile_guards(rmspec.G, cbt.Inv)  # 复用 IP-53，双源交叉
    assert trace_equiv(cbt, rmspec)            # 接受语言一致
    assert sound(monitor)                      # 单边可靠
    return Bundle(cbt, reward, monitor, version=rmspec.version)

def trace_equiv(cbt, rm):
    prod = product(flatten(cbt), rm)           # 有限状态，可枚举
    return all(accept_cbt(prod, w) == accept_rm(prod, w)
               for w in lasso_cover(prod))
```

### 2.5 与 IP-51 CAR 的集成
```
def sync_modes(H, T):
    # 把 CBT 的 Fallback 分支映射为 CAR 的恢复边，避免两套恢复逻辑打架
    for q in [Degraded, Escalate]:
        H.add_edge(q, target=recover_branch(T, q),
                   guard=Or(branch.Pre & branch.Cert for branch in T[q]))
    assert bisimilar(flatten(T), H)            # 展平后必须等价
```

## 3. 推导与数值示例

### 3.1 为什么塑形不能替代证书（定义 34 的严格含义）
设无约束 MDP 最优策略集为 Π*。对任意势 Φ 与任意 λ，回报满足
`E[Σ(r+λF)] = E[Σr] + λ·E[Φ(s₀) − γ^TΦ(s_T)]`。
当 γ<1 且 T→∞，第二项趋于常数 `λΦ(s₀)`，与策略无关，故 argmax 不变。**因此若某最优策略会违规，任何 λ 都救不了它**；塑形只能让「本就可行」的策略更快被找到。这直接推出设计原则：**屏蔽/约束是安全的一阶机制，Φ 是样本效率的二阶机制**，二者不可颠倒。

### 3.2 分块恢复时间够不够 E80 的门槛
UniBot 典型 T_a=8、控制 30Hz ⟹ τ_tick≈267ms。取树深 depth=4、τ_min=1 chunk，则最坏恢复 ≤4×267+267≈1.33s < E80 的 2s。若把 SafeStop 放在最深叶并加 Retry，深度每加 1 就多 267ms；因此**树深是可用性的硬预算**，E80 应同时报告 depth 分布。

### 3.3 屏蔽 regret 与守卫覆盖的统计含义
若屏蔽只删除「真违规」动作，则可行最优不变，regret=0；实际 regret 来自误屏蔽（把安全动作当违规），由边际保守性 ρ 决定，量级 `O(ρ·|A|)`。另一方面，零违规的 N 次采样只说明违规率上界约为 `1−α^{1/N}`（如 N=300、α=0.05 ⟹ 上界约 1%），**不能证明零风险**。故 E82 必须同时报告 N、置信度与 OOD 拒识率，禁止只报「0 违规」。

### 3.4 对齐间隙的分解（定义 36）
`H = H_proxy + H_cover`。前者是奖励与任务真值的代理误差，可由奖励审计直接测；后者是守卫集不完备带来的不可测部分，只能由 OOD 检测与在线重估间接估计。**本轮所有「安全」结论都只覆盖 H_proxy**，这是必须在论文里写死的边界。

### 3.5 一个最小的“恢复 vs 安全”权衡例
若把 θ 提高 Δθ，则 ValidRegion 缩小、T_hold=(m₀−θ)/L_m 缩短、误降级概率上升；但 Fallback 会在条件恢复后自动回 Nominal，于是**可用性对 θ 的敏感度被结构性恢复削平**。这解释了为什么 E80 的 Nominal 占比能从 v18 的 70% 提到 80%：收益主要来自恢复结构，而非更松的界。

## 7. 本轮最大风险

**一句话**：最大风险不是「奖励太弱学不会」，而是**对齐幻觉**——行为树保证「有路可回」、奖励塑形提升「实践边际」、屏蔽挡住「已知违规」，三者都很漂亮，却都建立在「守卫集完备 + 边际估计可信」这个未证前提上；一旦守卫漏掉一类危险或边际在 OOD 处系统性偏乐观，结构活性会让人误以为系统既安全又可用，实际上只是把失败推迟到分布外。
