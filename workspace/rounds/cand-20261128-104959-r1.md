### 第 6 轮灵感驱动研究记录（本轮循环第 1 轮）

**灵感词**：多机评测、工具调用

**继承关系**：承接第 5 轮 CADVS-v5（IP-493~496，Certified Generative Execution, CGE）：七硬门 fail-closed、证书不变性（定理 6）、调制单调性（定理 5）、固化有界（定理 7）、执行集 Exec_CADVS-v5 ⊆ … ⊆ Exec_v29。v5 把「提议器」一般化为任意生成器，但它的「动作原子」仍是**一条完整轨迹**、「验证单元」仍是**单台机器**。这两个隐含假设在真实部署里都不成立：(a) 真实系统由**工具/技能调用**组合而成（抓取、放置、移交、规划查询、感知服务），每次调用是一个「调用者—被调用者」契约，v5 只保证单条轨迹过门，不保证**组合**过门；(b) 真机是**机队**，动力学/运动学/传感器/标定各异，单机校准的证书不自动迁移到另一台机器，而多机评测本身又会被故障机/恶意机污染。两个灵感词统一为主题「认证的工具调用与机队评测」（Certified Tool Invocation & Fleet Evaluation, CTFE），形成 CADVS-v6（IP-497~500）。本轮自律：**逐轨迹硬门仍为七**；工具契约与机队评测是「组合层 + 证据层」，不新增逐轨迹门。执行集嵌套升级为 Exec_CADVS-v6 ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29。

**直觉与动机**：

1. **工具调用 → 动作原子从「整条轨迹」升级为「带契约的工具调用」，证书从「点验证」升级为「组合验证」**。直觉：单独认证过的锤子加单独认证过的钉子，并不保证「锤钉子」安全——前置条件、后置条件、副作用、资源争用都可能错配。引入 TCK：每个工具 τ 是类型化契约 (id, Args, Pre, Post, Obl, Fail, Res, Cost)。一次调用只有在 Pre 成立、参数落在**已认证参数域** Args_cert、且证书义务 Obl 被清偿时才被准入；调用后登记 Post。组合规则：顺序组合要求 Post_i ⇒ Pre_{i+1}；并行组合要求**互不干扰（non-interference）**且资源不相交。关键定理 9（组合证书可靠性）：若每次调用局部认证、且组合的 Pre/Post 链与互不干扰成立，则组合执行集 ⊆ 各步门交集，fail-closed 保持。这把 v5 的「任意生成器 + 认证边界」推进为「任意工具图 + 认证边界」——流策略不再直接吐低层轨迹，而是生成**工具调用程序**（tool-call program）：工具 id 序列与参数由流生成，合法性由契约约束。

   工具调用还引入 v5 完全没有的**攻击面**：参数通道可被注入——感知/记忆/语言给出的参数被污染、混淆代理（confused deputy）、越权调用、参数幻觉。引入 TCG：参数来源溯源（每个 arg 记录由哪个感知/记忆/工具产生）、模式与值域校验、最小权限能力令牌、工具身份由契约固定而非由模型文本决定。定理 10（参数封闭性）：若进入已认证工具的参数都来自已认证域、且能力令牌强制最小权限，则不可信内容无法把执行集扩出 Exec_v5——注入在结构上只能「触发 fail-closed」，不能「放松门」。

2. **多机评测 → 验证单元从「单机点估计」升级为「机队分布 + 抗拜占庭聚合」**。直觉：一台机器上 99.9% 通过，不代表机队 99.9% 通过；机队里可能有回差大、标定漂移、传感器退化的个体，甚至被攻陷、谎报评测结果的个体。引入 FEK：(a) 机队参数分布 e ~ P_E（连杆长度、摩擦、延迟、噪声、回差），用分布鲁棒优化在**歧义集** 𝒰_ρ(P̂_E) 上求最坏情况边际，证书要求 worst-case margin ≥ τ；(b) 统计评测用 Clopper–Pearson/保形给出通过率的**下置信界** LCB_{1−δ}，而非点估计；(c) 聚合用**拜占庭鲁棒**统计量（坐标中位数/截尾均值），容忍 f < n/3 台故障或恶意机，防止少数机刷高证书；多机**互评（peer evaluation）**模式下还要求签名报告 + 哈希链承诺，抵抗串谋。定理 11（机队评测可靠性）：在 f < n/3 拜占庭、诚实机报告可交换的假设下，鲁棒聚合给出的 LCB 以 ≥1−δ 覆盖诚实机队通过率下界；定理 12（跨机迁移的分布鲁棒界）：若证书在歧义集最坏情况满足门，则对歧义集内未见机器期望违例 ≤ ε；**诚实边界：歧义集外（真正 OOD 的新构型）无保证**。

**关键洞见**：v5 回答「提议是任意生成器时，证书边界如何不变」；v6 回答「动作是工具组合、验证对象是异构机队时，证书如何组合与迁移」。核心不是加门，而是把证书的**代数**从「单轨迹 × 单机」推广到「工具图 × 机队分布」：TCK 给组合律，TCG 守住参数通道，FEK 给机队统计界。七硬门 kc_evidence_forged_v5 记号原样复用；本轮新增的只有：工具契约的 Pre/Post/Obl、参数溯源标签、机队歧义集 𝒰_ρ(P̂_E) 与鲁棒 LCB。执行集 Exec_CADVS-v6 ⊆ Exec_CADVS-v5 由「同门 + 工具参数封闭 + 机队最坏情况边际只紧」三重保证。

**形式化目标（增量）**：
1. TCK 工具契约 τ=(id, Args, Pre, Post, Obl, Fail, Res, Cost)；工具调用 c=τ(a)，a∈Args_cert；调用图 G=(V_calls, E_seq ∪ E_par)。
2. 组合规则：顺序 Post_i ⇒ Pre_{i+1}；并行 non-interference ∧ Res_i ∩ Res_j = ∅；组合证书 CompCert(G) = ∧_v local_cert(v) ∧ chain ∧ nonint。
3. TCG 参数封闭：ArgProvenance(a) ⊆ TrustedSources ∧ a ∈ Domain_cert(τ) ∧ CapToken(τ) 最小权限；否则 fail-closed。
4. FEK：机队分布 P_E、歧义集 𝒰_ρ(P̂_E)（Wasserstein ρ-球）；worst-case margin m_wc = inf_{Q∈𝒰} E_Q[m]；鲁棒 LCB = 坐标中位数 + Clopper–Pearson。
5. 定理 9（组合证书可靠性）、定理 10（参数封闭/注入不可能放松门）、定理 11（拜占庭鲁棒机队评测）、定理 12（分布鲁棒迁移界，含诚实边界）。
6. Exec_CADVS-v6 = {执行工具图 G : CompCert(G)=1 ∧ θ∈Θ_fleet ∧ ∧_i kc_i=1} ⊆ Exec_CADVS-v5。

**本轮最大风险**：**契约框架条件不可完备、机队分布内过拟合**——工具契约的 Pre/Post/互不干扰只能覆盖「建模到的」副作用，真实开放世界里未建模的跨工具耦合（共享执行器热、共享工作空间、时序耦合、感知串扰）会悄悄击穿 assume-guarantee 链；而机队鲁棒界只在歧义集/采样分布内成立，评测机队越「配合」，越会把证书过拟合到「见过的那批机器」，两者叠加使证书可能「局部完美、整体失真」。

## 2. 关键算法骨架

### IP-497 TCK：工具契约核（离线编译契约；在线 O(|G|) 检查）

```python
@dataclass
class ToolContract:
    id: str
    args_schema: Any                 # 类型 + 值域（含 Args_cert 子域）
    pre: Callable[[State], bool]     # 前置谓词（覆盖/物理/人因/资源）
    post: Callable[[State, State], bool]
    obligations: list[str]           # 需清偿的证书义务（如 kc_val, kc_bal）
    fail_modes: list[str]            # 已枚举失败模式（域外 = 无保证）
    resources: frozenset[str]        # 占用的执行器/工作空间/传感器
    cost: float

@dataclass
class ToolContractKernel:
    """TCK：动作原子=工具调用；证书从点验证升级为组合验证。
    定理 9：局部认证 + 顺序链 + 并行互不干扰 ⇒ 组合可靠（前提：框架条件完备）"""
    contracts: dict[str, ToolContract]

    def admit(self, call, world: State, certs: CertStore) -> bool:
        t = self.contracts[call.id]
        if not t.pre(world): return False
        if call.args not in t.args_schema.cert_domain: return False   # 域外无保证
        if not all(certs.discharged(o, call) for o in t.obligations): return False
        return True

    def compose(self, G) -> bool:
        # 顺序：post_i ⇒ pre_{i+1}；并行：资源不相交且互不干扰
        for (u, v) in G.E_seq:
            if not implies(self.contracts[u].post, self.contracts[v].pre):
                return False
        for (u, v) in G.E_par:
            if self.contracts[u].resources & self.contracts[v].resources:
                return False
            if not non_interfering(u, v, G.world_model):           # 依赖框架条件
                return False
        return all(local_cert_ok(v) for v in G.V_calls)
```

### IP-498 TCG：工具调用守卫（在线 O(|a|)；每次调用前）

```python
@dataclass
class ToolCallGuard:
    """TCG：参数封闭。不可信内容只能触发拒绝，不能放松门（定理 10）"""
    trusted: set = frozenset({'perc_cert', 'mem_cert', 'prior_cert', 'const'})

    def check(self, call, prov: dict, cap: CapToken, t: ToolContract) -> bool:
        # 1) 来源溯源：每个实参必须来自可信来源
        if not all(set(prov[i]) <= self.trusted for i in range(len(call.args))):
            return False
        # 2) 值域：参数必须落在已认证参数域（域外工具保证失效）
        if call.args not in t.args_schema.cert_domain:
            return False
        # 3) 能力：工具身份由契约固定，令牌仅授予最小权限资源
        if not cap.allows(t.id, t.resources):
            return False
        # 4) 混淆代理：调用者不得借被调用者的更高权限；参数不得携带指令
        if contains_instruction_payload(call.args):
            return False
        return True

    # 说明：cert_domain 内的「数值合法但语义恶意」参数（如容忍范围内的
    # 对抗位姿）不在此层防护范围——属感知完整性，见 R61。
```

### IP-499 FEK：机队评测核（离线 DRO + 在线查表）

```python
@dataclass
class FleetEvaluationKernel:
    """FEK：验证单元=机队分布，不是单机点估计。
    定理 11（拜占庭鲁棒 LCB）+ 定理 12（分布鲁棒迁移界）"""
    rho: float = 0.05          # Wasserstein 歧义半径
    eps: float = 0.01          # 允许违例率
    delta: float = 0.05        # 置信水平
    tau_m: float = 0.0         # 最坏边际门槛

    def worst_case_margin(self, margins_by_e, P_hat) -> float:
        # inf_{Q: W1(Q,P_hat)<=rho} E_Q[m]；对 m 为 Lipschitz 时可由
        # Kantorovich-Rubinstein 对偶化为经验均值 − rho·Lip(m)
        return empirical_mean(margins_by_e) - self.rho * lipschitz_const(margins_by_e)

    def robust_lcb(self, reports) -> float:
        # reports: 各机通过率；坐标中位数抗 f<n/3 拜占庭
        p_tilde = coordinate_median(reports)
        n_eff = effective_sample_size(reports)
        return clopper_pearson_lower(p_tilde, n_eff, self.delta)

    def admits_fleet(self, theta, margins_by_e, reports) -> bool:
        m_wc = self.worst_case_margin(margins_by_e, None)
        lcb = self.robust_lcb(reports)
        return (m_wc >= self.tau_m) and (lcb >= 1 - self.eps)

    # 多机互评模式：报告须签名 + 哈希链承诺；聚合前剔除承诺冲突者，
    # 防串谋刷分（见 R63 的共同模式故障边界）。
```

### IP-500 EFA-v6：七硬门 + 工具图准入 + 机队证据

```python
@dataclass
class EvidenceForgingAssemblerV6:
    """EFA-v6：七硬门不变（逐轨迹门），新增组合层与机队证据层"""
    fmpp: FlowMatchingProposalPolicyKernel
    lmem: LongTermMemoryEmbeddingConsolidation
    famk: FacialAffectModulationKernel
    tck: ToolContractKernel
    tcg: ToolCallGuard
    fek: FleetEvaluationKernel
    v5: EvidenceForgingAssemblerV5

    def select(self, state, t_now, context) -> tuple[bool, Program | None, str]:
        s_emo = self.famk.observe(context.face, t_now)
        gamma = self.famk.gamma(s_emo)
        c = build_ctx(context, s_emo, self.lmem)
        # 第 0 层：流生成工具调用程序（工具 id 序列 + 参数），非低层轨迹
        progs = self.fmpp.propose_programs(c, K=self.fmpp.K)
        admitted = []
        for G in progs:
            # 第 1 层：TCG 参数封闭（来源/值域/能力/注入）
            if not all(self.tcg.check(call, G.prov, G.cap, self.tck.contracts[call.id])
                       for call in G.calls):
                continue
            # 第 2 层：TCK 组合证书（顺序链 + 并行互不干扰 + Obl 清偿）
            if not self.tck.compose(G):
                continue
            # 第 3 层：机队证据（θ∈Θ_fleet；m_wc≥τ；LCB 达标）
            if not self.fek.admits_fleet(G.theta, G.margins, G.reports):
                continue
            # 第 4 层：逐轨迹七硬门（复用 v5 级联；工具内部轨迹展开）
            ok, plan, why = self.v5.select_with_program(G, gamma)
            if ok:
                admitted.append((G, plan))
        if not admitted:
            return self._fallback_rule_program(gamma)   # fail-closed
        best = max(admitted, key=lambda gp: certified_margin(gp[0]))
        return True, best[0], 'FORGED_CTFE'

    def ecs_v6(self, base, m_wc, lcb) -> float:
        eta_tool = sigmoid(m_wc / self.fek.tau_m - 1.0)
        eta_fleet = sigmoid((lcb - (1 - self.fek.eps)) / self.fek.eps)
        return base * eta_tool * eta_fleet
```

### 集成流水线（v5 → v6）

```
离线/慢时域：
  契约编译：工具文档/接口 ──▶ TCK 契约（Pre/Post/Obl/Fail/Res）──▶ 契约回归测试
```

## 4. 正确性论证（增量更新）

### 定理 9（组合证书可靠性 / assume-guarantee 组合）

**陈述**：设每个调用 v∈V_calls 满足 local_cert(v)=1（Pre 成立、a∈Args_cert、Obl 清偿），且对每条顺序边 (u,v) 有 Post_u ⇒ Pre_v，对每条并行边 (u,v) 有 Res_u ∩ Res_v = ∅ 且互不干扰。则任何实现 G 的具体执行都落在各调用局部门的交集内，即 CompCert(G)=1 ⇒ Exec(G) ⊆ Exec_gate。

**证明**：对 DAG 作拓扑归纳。基础：源调用局部证书成立，执行后 Post 成立。归纳：顺序边保证后继 Pre 由前驱 Post 蕴含；并行边互不干扰意味着任一交错执行不改变对方 Pre/Post（frame condition）。故所有调用的门谓词沿执行保持，交集成立。∎

**诚实边界**：定理只在「世界模型的框架公理完备、互不干扰可判定」时成立；未建模的跨工具耦合会**违反前提**而非违反结论——因此工程上必须把互不干扰做成可测试的断言（见实验 c），而不是假设。

### 定理 10（参数封闭 / 注入不可能放松门）

**陈述**：若每次工具调用的实参 a 满足 prov(a) ⊆ TrustedSources、a ∈ Args_cert(τ)、CapToken 强制最小权限，则任意注入/不可信内容 u 都不能产生一个把执行集扩出 Exec_v5 的调用；u 的唯一可能效果是触发拒绝（fail-closed）。

**证明**：工具的可靠性保证以 a∈Args_cert 为条件，域外无保证 ⇒ 准入直接拒绝；来源检查阻断混淆代理（不可信来源无法借用高权限工具）；能力令牌限制工具只能触达授权资源，越权调用被拒。因此不可信内容只能落在「拒绝」分支，执行集不会因注入而扩张。∎

**诚实边界**：该定理不防「域内语义恶意」参数（如数值在容忍范围内、但对应被对抗篡改的物体位姿）；这属于感知完整性，需要独立于工具调用的感知证书，见 R61。

### 定理 11（拜占庭鲁棒机队评测）

**陈述**：n 台机器中至多 f < n/3 台拜占庭（可任意谎报），其余诚实机报告其真实通过率。以坐标中位数/截尾均值聚合得 p̃_rob，并在有效样本量上取 Clopper–Pearson 下界 LCB。则对诚实机队通过率 p_honest，P(LCB ≤ p_honest) ≥ 1−δ，且 p̃_rob 的崩溃点为 floor((n−1)/2)/n > 1/3。

**证明**：中位数/截尾均值的崩溃点结论给出：少于 n/2 的任意污染不能把估计推出诚实值的有界邻域（f<n/3 更保守）；再对有效样本量施加 Clopper–Pearson 的单侧覆盖，并用有限样本集中不等式吸收估计偏差，得 ≥1−δ 覆盖。∎

**诚实边界**：鲁棒性针对**独立**的拜占庭报告；对**共同模式故障**（所有机器共享同一标定错误/同一仿真器偏差）无效——此时中位数会一致地错。互评串谋需签名+承诺剔除，但无法排除「诚实但同偏」的系统性偏差。

### 定理 12（跨机迁移的分布鲁棒界）

**陈述**：若在歧义集 𝒰_ρ(P̂_E) 上 worst-case 违例率 ≤ ε（即 inf_{Q∈𝒰} P_{e~Q}(m<0) ≥ 1−ε 的对偶形式），则对任意测试机队分布 Q′ 满足 W_1(Q′, P̂_E) ≤ ρ，期望违例率 ≤ ε；对 W_1(Q′, P̂_E) > ρ 的分布无保证。

**证明**：由 𝒰_ρ 的定义，Q′∈𝒰_ρ 时最坏情况覆盖它；Wasserstein 对偶（Kantorovich–Rubinstein）给出边际函数 Lipschitz 时用 ρ·Lip 把分布漂移转成违例率漂移。∎

**诚实边界**：ρ 是建模选择而非从数据自动得出；真正的 OOD（新构型、新负载、新环境）落在球外，界失效。故 v6 只把机队评测当作「分布内证据」，不当作 OOD 安全证明。

### 定理 v6（组合与机队下的执行集收缩，总装）

**陈述**：在 v5 假设 (B1)~(B7) 及新增 (B8) 世界模型框架条件完备（定理 9 前提）、(B9) 机队采样可交换且 f<n/3 下：
(i) Exec_CADVS-v6 ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29；
(ii) 组合可靠性（定理 9）：局部认证 + 链 + 互不干扰 ⇒ 组合过门；
(iii) 参数封闭（定理 10）：注入只 fail-closed，不放松门；
(iv) 机队证据（定理 11/12）：LCB 覆盖诚实机队、DRO 界覆盖歧义集内迁移；
(v) 七锚完备性（v5 定理 8）保持；工具契约/机队评测是组合层/证据层，非新锚。

**证明**：(i) 由同门 + 工具参数封闭 + 机队最坏边际只紧；(ii)(iii)(iv) 分别由定理 9/10/11/12；(v) 锚集合不变。∎

**诚实声明**：(B8) 是强假设，真实开放世界的跨工具副作用难以枚举；(B9) 的「可交换 + 独立拜占庭」在共同模式故障下失效；(iii) 不覆盖感知完整性；(iv) 不覆盖歧义集外 OOD。以上四条是本轮明确不解决、只做限损的边界。

## 5. 实验设计与初步结果（仿真，单机；真实机队列入第 7 轮）

### 5.1 实验设计

- **平台**：MuJoCo 3.x + MJX 机队仿真：N=32 台，3 种机器人模型，参数随机化（质量 ±20%、摩擦 ±30%、延迟 0–20 ms、回差、传感器噪声）；工具库 12 个（抓取/放置/移交/推/拉/查询规划/感知重定位等），每个工具有类型化契约。
- **对照**：v5-single（单机点估计）、v6-fleet（DRO+鲁棒 LCB）、消融 A11（v6 去 TCK 组合检查）、A12（v6 去 TCG 参数封闭）、A13（v6 用均值聚合替代鲁棒聚合）、A14（v6 用点估计替代 DRO）。
- **场景**：(a) 机队异质性迁移（训练机队 → 留出机队族）；(b) 拜占庭注入（f=5/32 谎报通过率）；(c) 工具调用注入（域外参数、混淆代理换工具、参数夹带指令）；(d) 组合干扰（共享工作空间/执行器的 3–5 工具序列）；(e) 共同模式故障（全体共享同一标定偏差）。
- **指标**：机队通过率 LCB、最坏边际 m_wc、证书膨胀率（拜占庭下）、注入攻击成功率、组合违例率、留出机队族迁移违例率、每采纳任务契约检查开销、OOD 检出率。

## 7. 本轮最大风险（最终确认）

**一句话**：**契约框架条件不可完备、机队分布内过拟合**——工具契约只能覆盖建模到的副作用，未建模的跨工具耦合会击穿 assume-guarantee 链，而机队鲁棒界只在歧义集/采样分布内成立，两者叠加使证书可能「局部完美、整体失真」。
