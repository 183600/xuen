# 第 46 轮（承接第 45 轮 v10；本轮灵感：多任务学习 × 开源软件） · Multi-Task-Cert × Open-Cert-Commons：多任务共享表征下的证书耦合与开源证书供应链的可审计治理（四层架构 v11）

> 承接第 45 轮 v10 Energy-Context-Depth。v10 把姿态证书放进了能量租约 ℓ_e 与上下文预测的联合调度，但隐含假设 H5：证书与校准器是「单任务、内部生产、任务集固定」的。真实 UniBot 同时跑导航、抓取、跟随、对接、安全监控等任务，几乎必然共享一个视觉骨干；内部标注与共形校准无法覆盖长尾，而开源生态可以贡献数据集、权重与校准器，却带来溯源、复现、负迁移与供应链投毒问题。两个灵感词精确命中 H5：**多任务学习**说明共享表征让证书跨任务耦合，更新任务 A 可能悄悄抬高任务 B 的半径（负迁移）；**开源软件**说明证书生产可以众包，但必须像软件供应链一样具备 CBOM、锁文件、复现 CI、社区审计与 CVE 式撤销。二者耦合出新问题：**当校准器来自开放共同体、且多任务共享骨干持续更新时，如何保证每个任务的证书组合仍然 sound，并阻止恶意/劣质证书工件以「更新更优」的假象静默进入部署**。

## 0. 直觉与动机

**灵感 1（多任务学习 → 证书耦合、负迁移与任务分组）**
直觉：多任务共享骨干像一条公共高速公路，任务 A 的施工会封掉任务 B 的车道。共形半径 r_ω 依赖于共享表征 θ，因此 θ 的任何更新都会同时改写所有任务的分层半径；「平均精度提升」完全可能伴随某个安全关键任务在最坏层上的半径膨胀。于是证书必须从点升级为**证书组合** C_t={P_t^{(k)}}_{k∈K}，并引入跨任务证书干扰算子 I_{j→k}：用硬预算约束更新，把安全关键任务隔离到私有头与私有校准，只在干扰可证的范围内共享。

**灵感 2（开源软件 → 证书供应链与可审计共同体）**
直觉：开源的真正贡献不是「免费」，而是**可追溯的分工**。把每个校准器、权重、数据集清单、分层半径表视为一个工件，建立 CBOM（Certificate Bill of Materials）与溯源 DAG；部署用 CertLock 锁定哈希与半径，用复现 CI 验证可重放，用独立审计 q-of-n 准入，用 CVE-C 撤销已知坏分层。这样「社区贡献」既保留规模优势，又具备软件供应链级别的追责能力。

**灵感 3（二者耦合 → 准入即证明，回滚即安全）**
直觉：开源共同体可以持续供给新证书，但只有当它同时通过**溯源完整性**与**跨任务证书预算**两道门时才可进入部署。任何一次共享骨干更新或社区工件更新，都要么被证明对所有任务干扰 ≤ 预算，要么被任务分组隔离，要么被 CertLock 拦在门外。准入不是投票，而是「证明 + 可复现 + 可撤销」。

**架构升级**：在 v10 之上引入**证书组合**与**横切的开源证书共同体治理面 OCC**。v11：根信任层新增 CertLock 与撤销表；L1 几何层输出任务索引证书组合 P_t^{(k)}、r_{ω,k}(m)；L2 上下文层按任务条件化预测；L3 CAR 守卫改为组合守卫并校验供应链；L4 DCL 采集带溯源贡献与去重/投毒检测；OCC 横切负责 CBOM、复现、审计、准入与撤销。

## 1. 形式化定义（增量：定义 54–58）

**定义 54（多任务证书组合与跨任务干扰）**
任务集 K={1,…,K}，共享表征 z=f_θ(x)，任务头 g_{ψ_k}。任务 k 的分层共形半径 r_{ω,k}(θ,ψ_k;D_cal)。证书组合
C_t={P_t^{(k)}}_{k∈K}，soundness 要求 ∀k：P(X_t^{(k)}∈P_t^{(k)} | ω_t,m_t) ≥ 1-α_k。
对任务 j 上的更新 θ→θ'_j，跨任务证书干扰
I_{j→k}(θ,θ'_j)=max_ω [ r_{ω,k}(θ'_j,ψ_k)-r_{ω,k}(θ,ψ_k) ]_+ / r_{ω,k}(θ,ψ_k)。
**证书预算**：更新可接受当且仅当 ∀k∈K_safe：I_{j→k}≤B_k，且 ∀k：I_{j→k}≤B_k^max。负迁移 = 存在 k 使 I_{j→k}>0 且更新目标不含 k。

**定义 55（证书物料清单 CBOM 与溯源 DAG）**
工件 a=(h_θ,h_c,M_D,strata,L,A_parents,A_att,sig)：模型哈希、校准器哈希、数据集清单（含采集护照摘要）、分层映射、许可证、父工件集合、审计背书、签名。
溯源 DAG G_CBOM=(A,E_parent)，边表示「由父工件推导」。部署锁文件
CertLock={(a_i,h_i,r_{ω,k}^{(i)},τ_exp)}。
**可追溯**：任意部署工件在 G_CBOM 中存在到受信任种子集合 S_0 的路径。

**定义 56（开源证书共同体准入谓词）**
工件 a 关于图 G_CBOM、撤销表 Rev、信任种子 S_0 可准入：
Adm(a)=Repro(a) ∧ (#独立审计≥q) ∧ LicCompat(L) ∧ (strata(a)∩ActiveCVE(Rev)=∅) ∧ Rooted(a,S_0)。
其中 Repro(a) 要求同输入下半径表逐位一致，或在预先声明的统计容差内重放一致；ActiveCVE 是 CVE-C（Certificate Vulnerability Enumeration）式的分层级撤销。

**定义 57（证书锁与可复现部署）**
部署时对每个运行工件校验
LockOK(a,t)= (hash_runtime(a)=h_a) ∧ (a∉ActiveCVE) ∧ (t≤τ_exp(a))。
任一失败触发 fail-closed。CertLock 使 fork/依赖混淆/回放旧工件都无法静默改变 r_{ω,k}。

**定义 58（干扰感知任务分组与证书预算分配）**
选择分组 G={G_1,…,G_m}（同组共享主干，不同组独立头）与参数预算 b：
min_G max_{k∈K_safe} I_{group→k}(G)  s.t.  Σ_{g} cost(G_g) ≤ C,  K_safe⊆私有头,  I_{j→k}≤ε (∀共享对)。
安全关键任务（安全谓词直接依赖的任务）永不共享头；非安全任务按任务亲和度矩阵 Aff(j,k)=1-I_{j→k} 聚类，形成「证书感知的任务分组」。

## 2. 新增产出与既有 IP 升级

**IP-66 MT-CERT BROKER（多任务证书经纪）**
- 证书组合签发：按任务索引半径表 r_{ω,k}(m)，输出 C_t
- 跨任务干扰监测：每次骨干/头更新前重算 I_{j→k}，超预算即拒绝
- 任务亲和度矩阵 + 证书感知分组：安全任务私有头，非安全任务聚类共享
- 证书预算账本：记录每任务历史干扰与最坏层半径，支持审计

**IP-67 OPEN-CERT COMMONS（OCC，开源证书共同体）**
- CBOM 生成与溯源 DAG 维护：模型/校准器/数据集/护照全链路
- 复现 CI：半径表重放、统计容差、签名校验
- 社区准入：q-of-n 独立审计、许可证兼容检查、分层级 CVE-C 撤销
- 投毒/搭便车检测：重复样本、异常半径压窄、来源单点集中度告警

**IP-68 CERT-LOCK SUPPLY-CHAIN GUARD**
- CertLock 锁文件：哈希 + 半径 + 过期时间
- fork/typosquat/依赖混淆检测：工件命名与来源图异常
- 撤销传播：CVE-C 命中即级联失效相关任务证书
- 回滚证明：旧锁文件可重建、可复现

## 3. 算法骨架

MTCB 在每个更新窗口：
1. 收集候选更新 Δ（共享骨干或任务头）与候选社区工件 a
2. 对 a 执行 OCC 准入：Repro、审计数、许可证、ActiveCVE、溯源
3. 重算所有任务的 r_{ω,k} 与 I_{j→k}；检查证书预算 B_k
4. 超预算 → 尝试任务分组隔离；仍超 → 拒绝更新（保留旧 CertLock）
5. 通过 → 更新 CertLock、证书组合 C_t 与总线
CAR 每次守卫：先 LockOK 与撤销校验，再按任务 k 取 P_t^{(k)} 做鲁棒提升。
DCL 将失败样本与负迁移样本带护照回灌 OCC，供社区复现与再校准。

## 4. 本轮最大风险

**一句话**：多任务共享骨干的负迁移会在更新非安全任务时悄悄抬高安全关键任务的最坏层半径，而开源共同体的众包校准又可能引入投毒或溯源断链，两者叠加会让证书组合在「指标更优、版本更新」的假象下静默失效；因此必须以安全任务私有头与证书预算硬约束隔离干扰，并用 CertLock、CBOM 溯源、q-of-n 独立审计与 CVE-C 撤销共同兜底。

## 2. 关键算法 伪代码

### IP-66 MT-CERT Broker
```
def recompute_radii(model, calib, tasks, m):
    return {(k, w): conformal_radius(model.head[k], calib[k][w], m)
            for k in tasks for w in Omega}

def cross_task_interference(old_r, new_r, tasks):
    I = {}
    for (k, w) in old_r:
        I[k] = max(I.get(k, 0.0),
                   max(0.0, (new_r[(k, w)] - old_r[(k, w)]) / old_r[(k, w)]))
    return I

def admit_update(model, delta, cert_book, budgets, K_safe):
    old = cert_book.radii
    cand = apply(delta, model)
    new = recompute_radii(cand, cert_book.calib, cert_book.tasks, cert_book.m)
    I = cross_task_interference(old, new, cert_book.tasks)
    for k in K_safe:
        if I[k] > budgets[k]:
            if try_private_head(cand, k, cert_book):
                return Accept(grouped=True, interference=I)
            return Reject('negative_transfer', task=k, value=I[k])
    if max(I.values()) > budgets['max_all']:
        return Reject('global_budget', value=max(I.values()))
    return Accept(grouped=False, interference=I)

def group_tasks(tasks, affinity, eps, K_safe):
    # 安全任务永不共享头
    shared = [k for k in tasks if k not in K_safe]
    groups = agglomerative(shared, key=affinity, stop=max_cross <= eps)
    return groups + [[k] for k in K_safe]
```

def lock_check(lock, runtime, rev, t):
    for a in lock.artifacts:
        if runtime.hash(a) != lock.h[a]:   return FailClosed('lock_mismatch')

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| 跨任务干扰重算 | O(|K|·|Ω|·|M|) 每次更新 | O(|K|·|Ω|·|M|) | 全任务重算 ⇒ 负迁移不被漏检 |
| 证书感知分组 | O(|K|^2 log|K|) | O(|K|^2) | 安全任务私有头 ⇒ 干扰隔离 |
| OCC 准入 | O(|D|+|G_CBOM|) | O(|G_CBOM|) | 复现 ∧ 审计 ∧ 溯源 ⇒ 工件可信 |
| CertLock 校验 | O(|A_lock|) 每守卫 | O(|A_lock|) | 哈希/撤销/过期任一不符 ⇒ fail-closed |
| 证书组合 C_t | O(|K|) | O(|K|·|Ω|·|M|) | ∀k 覆盖 ≥1-α_k ∧ 供应链可信 ⇒ 组合 sound |

**正确性定理（v11）**：若 (i) 部署满足 LockOK 且无 ActiveCVE；(ii) 每个任务 k 的更新满足 I_{j→k}≤B_k（或已被私有头隔离）；(iii) P_t^{(k)} 满足定义 44 的条件覆盖；(iv) 能量租约 ℓ_e 与姿态租约 ℓ_p 有效；则证书组合 C_t 的鲁棒提升 φ_k^□(P_t^{(k)}) 对每个任务 sound。任一条件失效 → fail-closed 或拒绝更新，不允许「部分任务静默降级」。

**回退**：E109 负迁移不可控 → 安全任务全部私有头并冻结共享骨干；E111/E112 工件不可信 → 只用 S_0 内部工件 + CertLock 只读；E113 锁不一致 → 停止更新并回滚到上一个已复现锁；E114 能耗劣化 → 降低非安全任务频率。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 负迁移静默抬高安全任务半径 | 高 | 全任务重算干扰 + 硬预算 + 安全任务私有头 + 拒绝更新 |
| 社区校准器投毒/半径异常压窄 | 高 | 复现 CI + q-of-n 独立审计 + 半径收缩 z 检验 + 来源集中度告警 |
| 溯源断链/未审计 fork 混入 | 高 | CBOM 溯源 DAG + CertLock + 未审计 fork 拒绝 |
| 审计者共谋或搭便车 | 中 | 审计者多样化 + 抽样复算 + 信誉与撤销 |
| CertLock 过期导致长期用旧校准 | 中 | 过期强制再准入 + 回滚证明 + 安全停机 |
| 任务分组过度碎片化 | 中 | 参数预算 C + 亲和度阈值 + 合并低风险组 |

## 6. 本轮最大风险

**一句话**：多任务共享骨干的负迁移会在更新非安全任务时悄悄抬高安全关键任务的最坏层半径，而开源共同体的众包校准又可能引入投毒或溯源断链，两者叠加会让证书组合在「指标更优、版本更新」的假象下静默失效；因此必须以安全任务私有头与证书预算硬约束隔离干扰，并用 CertLock、CBOM 溯源、q-of-n 独立审计与 CVE-C 撤销共同兜底。
