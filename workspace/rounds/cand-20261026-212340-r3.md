# 第 8 轮 · SPD：分割是空间语言，蒸馏是合规通道，主动交互是盲区补丁

> 检索/复核日期：2026-10-26（UTC）。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「语义分割」「模型蒸馏」「主动交互」。我先做三处事实纠偏（排名规则、评测规模、榜单性质），再把三个词各自钉到官方事实与公开证据上，最后合成一个判断：**这届比赛缺的不是更大的 VLA，而是一套“看得懂物体与关系”的空间接口，以及把这些监督塞进一个 checkpoint 的合规通道；主动交互只用来补分割看不见的透明、遮挡和人为干扰。** 三者不是三条战线，而是一条链：分割定义状态，蒸馏让状态进得来，主动交互补状态看不见的残差。

## 0. 本轮先纠偏：三个会改变资源分配的事实

### 0.1 排名是成功率的字典序，不是步骤分的加权和

官方手册写得很清楚（[S6][S7]）：

```text
实时榜单按 32 个任务的总平均成功率排序；
成功率相同时，按总平均步骤分排序；
若仍相同，提交日期较早的模型排序靠前。
```

这意味着：

- **步骤分只在成功率打平时才起作用**。第 7 轮把“终局步骤占 39.8%、放置类占 59.7%”当作“步骤分大头”，方向没错，但目标函数要改写：**先最大化完整成功率，再谈步骤分**。一个把 T27 从“叠到第二层但没叠第三层”变成“完整叠三层”的改动，价值是成功率 +1 个 episode；一个只把某步从 30 分做到 40 分、但整任务仍失败的改动，在排名上几乎不值钱。
- **“部分完成但失败”的 episode 只能通过步骤分在平局时体现**，不能替代成功。上一轮从占位榜单推出的“步骤分−成功率 ≈ 8.6pp，所以失败集中在后段”只是弱先验；本轮不把它当证据（见 0.3）。
- 因此本轮的研究目标从“把步骤分做高”改为“**把失败 episode 翻成成功**”。语义分割、蒸馏、主动交互都必须回答同一个问题：它们是否提高完整成功率，而不是只让过程看起来更完整。

### 0.2 评测是 320 个 episode，每个轴只有 64 个；官方一次跑只能可靠检测约 10pp

手册与任务页（[S1][S2][S6]）：每个任务 10 次独立运行，5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰）各 2 次；32 个任务合计 **320 个 episode**。于是：

```text
每个 episode 对总成功率的权重 = 1/320 = 0.3125pp
每个任务满分权重           = 10/320 = 3.125pp
每个泛化轴                 = 64 个 episode（20%）
```

在总体成功率 p≈0.3 时：

| 统计量 | 数值 | 含义 |
|---|---:|---|
| 总体标准误 | √(0.3×0.7/320) ≈ **2.56pp** | 一次官方跑的 95% CI 约 ±5pp |
| 单轴标准误 | √(0.3×0.7/64) ≈ **5.73pp** | 轴级结论非常 noisy |
| 单任务标准误 | √(0.3×0.7/10) ≈ **14.5pp** | 不要用单任务 10 次跑下结论 |
| 检测 +3pp 所需/组 | ≈ **3,700 episodes** | 官方一次跑远不够 |
| 检测 +5pp 所需/组 | ≈ **1,350 episodes** | 需要多次提交或离线配对 |
| 检测 +10pp 所需/组 | ≈ **350 episodes** | 约等于一次官方跑的规模 |

**这条算术决定策略**：官方 320-episode 跑是“终局确认”，不是“日常迭代”。日常必须用离线 replay、配对种子、分层贝叶斯和小规模调试槽；否则会把 2–3pp 的噪声当成方法收益，或者把真正 5pp 的改动误杀。后文所有“预期收益”都标出可检测性，不把 1–2pp 的离线差异当承诺。

### 0.4 数据没有 depth/mask，但头戴双目已标定；空间监督是真正的缺口

HangCup 的 `meta/info.json`（[S4]）给出：

```text
total_episodes = 1043
total_frames   = 194,564
fps            = 30
4 路 RGB       = head_stereo_left/right + wrist_left/right，480×640
features       = 图像 + 关节/EE/夹爪/躯干/waist + action；没有 depth、没有 mask
camera_params.head_stereo:
  rectified = true
  T = [-58.2526, -0.1675, 0.5786] mm   → 基线 B ≈ 58.25mm
  fx ≈ 282.37 / 281.87 px，fy ≈ 282.75 / 282.32 px
```

双目能给出度量深度，但精度只够“粗 3D”。按视差 1px 估算：

| 距离 | 深度误差/px | 能做什么 | 不能做什么 |
|---:|---:|---|---|
| 0.3m | ≈ 5.5mm | 腕部近景抓取、粗定位 | 亚毫米插入 |
| 0.5m | ≈ 15.2mm | 桌面物体中心、容器口 | 精密对孔 |
| 0.8m | ≈ 38.9mm | 场景布局、支撑面 | 小零件位姿 |
| 1.0m | ≈ 60.8mm | 粗略避障 | 任何精密操作 |

所以本轮不把“双目深度”当精密测量，而把它当**3D 掩码的抬升骨架**：用分割得到物体/部件/容器的像素支持，用双目点云得到相对位置与尺度，用腕部近景和 EE 伺服完成最后几厘米。数据集没有 mask，恰恰说明**mask 必须由模型自己学出来**——这既是缺口，也是本轮方法的入口。

## 1. 语义分割：不是“多一个感知头”，是单模型的空间语言

### 1.1 五个泛化轴，本质都是物体级几何关系的变化

手册的 5 类泛化（[S6][S7]）看起来是 5 个独立条件，但把它们翻译成物体级变量，会发现它们是同一组变量的不同扰动：

| 泛化轴 | 官方定义 | 物体级变量 | 2D 外观模型为什么容易崩 |
|---|---|---|---|
| 位置 | 改目标物体初始位置/目标区域位置 | 物体中心、朝向、支撑面 | 绝对像素坐标记忆；背景相关性 |
| 干扰物 | 随机放入杂物 | 物体集合、遮挡关系、路径可通行性 | 把干扰物当目标；注意力被纹理带走 |
| 桌面背景 | 换桌布颜色/纹理 | 背景与物体的边界、光照 | 背景纹理进入决策；颜色偏置 |
| 未见物品 | 同类但外观不同（颜色/形状/材质） | 类别、形状、可供性、部件 | 外观记忆；类别内形状差异 |
| 人为干扰 | 执行中临时改变物体位置 | 物体状态变化、关系破坏、时序 | 开环 chunk；没有状态跟踪 |

如果模型内部只有“图像 token + 语言 token”，它必须从像素相关性里隐式学出这些变量；OOD 一来，相关性断裂。**语义分割把“哪个物体、在哪里、和谁有什么关系”变成显式的、物体中心的 token**，这是对五轴同时起作用的接口，而不是只对“背景”一个轴有用的预处理。

### 1.2 公开证据：mask 作为接口，在规划、 grounding、数据效率上都成立

| 工作 | 做法 | 关键结果 | 对本轮的启示 |
|---|---|---|---|
| **RAMP-3D**（[S15]） | 把长程 3D 装箱规划写成“选哪个物体 mask + 放到哪个目标区域 mask”的序列反应式预测；RGB-D 输入 | 11 个任务变体、1–30 个箱子，**79.5%** 长程成功率，显著优于 2D VLM 基线 | “物体 mask + 目标区域 mask”可以直接作为动作条件，不必先转成符号状态 |
| **SG-VLA**（[S17]） | 多视角 RGB + depth cues + 短时序；辅助解码器重建分割 mask、目标相对位姿、抓取可供性 | 在 pick/place/open/close 上稳定优于直接模仿学习 | 分割 mask 作为**辅助监督**能改善共享表征，不需要推理时额外模型 |
| **SEVO**（[S18]） | 实时 YOLO 分割 overlay + 主动红光照 + 多样化采集；不改策略结构 | ACT 训练环境 95%、新环境 85%；SmolVLA 83%/75%；无 SEVO 时新环境崩到 30–35% | 分割 overlay 能显著提跨环境鲁棒性；但“数据多样性”才是第一因素，分割是接口不是万能药 |
| **YUBI-STAG**（[S19]） | 接触物体分割 + VLM 自动标注物体身份/属性/状态/哪只手/空间关系；再蒸馏成 YUBI-VLM（仅腕部视角、少次推理） | 标注质量接近教师、推理调用更少；用这些标注后训练 VLA，双臂指令跟随提升 | “分割 + 关系标注 → 蒸馏进策略”正是本轮 PSD 的路线；且腕部视角足够做接触级标注 |
| **PokéVLA**（[S16]） | 2.4M 样本的紧凑 VLM 预训练（空间 grounding/可供性/具身推理）；多视角 goal-aware 语义 + 几何对齐 + action expert | LIBERO-Plus SOTA，真机扰动下更稳 | 空间 grounding 可以作为预训练目标，不必依赖巨大模型 |

这些证据合起来说明：**分割不是“感知模块”，而是“把语言目标落到物体/区域上的接口”**。RAMP-3D 证明物体 mask + 目标区域 mask 足以驱动长程操作；SG-VLA 证明 mask 辅助监督能改表征；YUBI-STAG 证明关系标注可以蒸馏；SEVO 证明分割 overlay 在跨环境时有用，但数据多样性不能省。

### 1.3 我们要的不是 2D 语义类，而是三类 3D mask

“语义分割”在自动驾驶里是“每个像素的类”；在本赛里，类标签不是最有用的，**实例/部件/容器**才是有用的。本轮定义三类 mask：

1. **物体 mask（object）**：可抓取/可移动的实例。用于“抓哪个”“现在在哪”“是否被拿走”。
2. **部件 mask（part）**：把手、壶嘴、插头尖端、拉链头、瓶盖、铰链、按键。用于精密接触和插入。
3. **容器/目标区域 mask（container/slot）**：碗口、杯架、插排孔、笔盒内部、书架层、传送带分类区。用于“放到哪”“是否放进去”。

三类 mask 都从多视角 RGB + 双目点云抬升到 3D：

```text
2D mask (per view) + stereo depth + camera params
  → 反投影到 base 系点云
  → 多视角关联（IoU/特征/3D 近邻）
  → 3D 实例点集
  → 中心、包围盒、主方向、支撑面、容器内部自由空间
```

3D 化带来四个 2D mask 没有的能力：

- **关系谓词**：`on(bowl2, bowl1)`、`in(plug_tip, socket)`、`closed(lid)`、`aligned(zipper)` 都可以用 3D 中心/法向/重叠/间隙定义，而不是 2D 像素重叠。
- **遮挡推理**：多视角下被遮挡的物体仍有部分点云；2D 单视角会直接丢。
- **尺度/位姿**：容器系相对位姿、物体对称轴、插入方向，都是 3D 量。
- **变化检测**：人为干扰表现为 3D 中心/关系的跳变；比像素差分更抗背景/光照。

### 1.4 为什么必须是“内部头”，不能在线调 SAM/YOLO

单模型规则是硬约束：手册写“所有任务须基于同一模型完成，不得混合使用多个模型一起进行测试”（[S6][S7]）。在线加载 SAM2 + GroundingDINO + 深度模型 + 策略，至少是 4 个模型；即使包装成一个服务，也有合规风险。再加上：

- **延迟**：评测按 step 记录 latency/variability/action regularity（[S5] §6）；每次 `get_action` 都跑一个大分割模型，p99 会炸。
- **OOD**：公开分割模型在桌面小物体、透明/反光、腕部近景上并不稳；它们的错误会直接进策略。
- **接口**：评测只给 4 路 RGB + proprio + language，没有 depth/mask；所有空间量必须由模型自己从 RGB 推。

所以本轮的路线是：**教师只在离线用，学生把分割/深度/位姿能力蒸馏进同一个 checkpoint**。推理时只有一个模型，mask 头是它的一部分；这不是“多模型集成”，而是“一个模型多任务”。

## 2. 模型蒸馏：用教师补空间监督，用学生守单模型规则

### 2.1 单模型规则下的“教师 loophole”：训练可以用，推理不能用

官方没有禁止离线使用任何教师/预训练权重；它禁止的是“测试时混合多个模型”。因此合规的边界是：

```text
训练期：教师集合（分割/深度/位姿/动作）可以任意大、任意贵；
推理期：只加载一个 student checkpoint；教师权重不加载、不调用；
确定性代码：反投影、PnP、谓词阈值、状态机不是“模型”，但要在模型卡披露。
```

这条边界是本轮所有蒸馏设计的前提。我们不是“用分割模型做推理”，而是“用分割教师生成监督，把能力压进学生”。

### 2.2 公开证据：多教师、on-policy、特权信息、chunk 对齐都能蒸馏

| 工作 | 蒸馏什么 | 关键结果 | 对本轮的启示 |
|---|---|---|---|
| **Multi-Teacher OPD**（[S20]） | 多个冻结领域专家 → 一个 flow-based VLA 学生；两级 on-policy：环境观测 + 学生生成的动作流轨迹上的教师速度监督 | LIBERO-40 **+22.55pp**、CALVIN 5 指令 **+33.4pp**、Meta-World MT50 **+22.6pp**；比 Action Loss OPD/Teacher-rollout SFT 高 6.4–9.5/9.7–18.3/3.2–4.2pp | 多教师可以合成一个学生；**on-policy 学生状态**比纯离线模仿更抗分布漂移 |
| **VLA-AD**（[S21]） | 离线 VLM 语义监督（任务阶段锚点 + 多帧操作方向）→ 轻量学生；测试时无教师/VLM | OpenVLA-7B → 158M 学生，**44×** 压缩，平均相对差距 **0.27%**，RTX 4090 **12.5Hz**、**3.28×**；可迁移到 π0.5-4B | 语义/阶段信号可以作为蒸馏目标，且能大幅压小模型 |
| **Shallow-π**（[S22]） | 同时减 VLM 主干与 flow action head 的层数（18→6） | **>2×** 推理加速，成功率绝对下降 **<1%**；Jetson Orin/Thor、人形真机 | 如果 mask 头让延迟超标，层蒸馏是部署侧的保险 |
| **PFD**（[S23]） | 把“看到未来”的教师残差蒸馏进 current-only 学生的小 adapter | LIBERO/RoboTwin 稳定提升；推理不生成未来视频、延迟近零 | “特权信息”可以是未来/几何，不一定是动作；mask/pose 也可视为特权 |
| **DreamMimic**（[S24]） | 特权教师（状态/接触/物体状态/奖励）→ 视觉人形控制器；world-model 辅助 | OMOMO/BEHAVE 优于强视觉基线；部署不暴露特权状态 | 人形 + 接触丰富任务可以用特权蒸馏；辅助头（接触/物体状态）是关键 |
| **CASD**（[S25]） | 离线 VLM 把演示切成阶段，生成 chunk 对齐的语义目标；冻结生成器，策略条件化 | DreamZero+CASD 在 MolmoSpaces 四类操作 **47.9% vs 40.7%**；RoboTwin **93.0% vs 90.6%** | 语义目标要对齐整个 action chunk，而不是只对齐 chunk 第一帧 |

这些结果的共同结构是：**教师可以是特权/多模态/更大/看到未来的；学生只保留推理时可得的信息；蒸馏损失要落在学生自己会访问的状态上**。这正是我们把 3D mask/pose/contact 教师压进一个 6B 学生的理论依据。

### 2.3 本轮的 delta：不是“蒸馏动作”，是“蒸馏空间状态”

已有蒸馏工作大多蒸馏动作/语义阶段/未来残差；本轮蒸馏的是**物体级 3D 状态**：

```text
教师看到的：2D/3D mask、双目深度、物体/容器 6D 位姿、接触/支撑/包含关系、阶段谓词、未来动作速度
学生看到的：4 路 RGB + proprio + language
学生要学的：mask logits、depth、3D 中心/包围盒/主方向、容器系相对位姿、谓词、动作 chunk
```

这比“只蒸馏动作”多两层好处：

1. **可解释的中间量**：mask/pose 错在哪，可以直接诊断；动作错了但 mask 对，说明是控制/接触问题；mask 错了，说明是 grounding 问题。
2. **跨任务共享**：物体/容器/部件的几何是 32 任务共享的；动作是任务特定的。蒸馏空间状态相当于给所有任务加了一个共享的几何先验。

同时保留“部署蒸馏”作为第二道保险：如果 6B + mask 头在目标 GPU 上 p99 超过预算，用 Shallow-π 的层蒸馏或 VLA-AD 的语义蒸馏压到更小；但主线不是“为了小而蒸馏”，而是“为了把教师的空间能力装进一个模型而蒸馏”。

### 2.4 合规写法：一个 checkpoint，教师零调用

我们会在模型卡里明确：

```text
Inference graph:
  images + proprio + language
    → shared VLM backbone
    → mask/depth/pose heads (same checkpoint)
    → predicate head (same checkpoint)
    → action expert (same checkpoint)
  No external model is loaded or called at inference.
  Teachers (SAM2/GroundingDINO/FoundationStereo/FoundationPose/larger VLA)
  are used offline for pseudo-labels only.
  Deterministic geometry (back-projection, PnP, thresholding) is code, not a model.
```

如果评测方要求“单模型”包括所有学习组件，这个图仍然成立：mask 头、谓词头、action expert 都是同一个 checkpoint 的子模块。若把 mask 头做成独立冻结网络再加载，就会踩线；本轮明确不做。

## 3. 主动交互：只补分割看不见的残差

### 3.1 被动分割的四类盲区

| 盲区 | 物理原因 | 被动 mask 的表现 | 主动交互能做什么 |
|---|---|---|---|
| 透明/反光 | 折射/镜面；双目匹配失效 | mask 边界碎、深度空洞、位姿跳 | 腕部侧视、改变光照/视角、轻推让边缘产生运动视差 |
| 遮挡 | 干扰物/容器壁挡住目标 | 目标 mask 缺失或只剩一小块 | 腕部绕视、轻推干扰物、抬起容器 |
| 人为干扰 | 执行中物体被移动/拿走 | mask 跟踪丢失、关系谓词从 1→0 | 重新观察、重新定位、回滚步骤、重抓 |
| 未见物品 | 外观/形状与训练不同 | 类别/部件混淆、抓取点错 | 多视角/近距离观察、试抓、根据形状调整 |

这四类恰好对应五轴里最难的“干扰物、未见物品、人为干扰”，以及透明物体密集的 T14/T32/T10/T26。光靠被动 RGB 分割，边界案例会一直丢。

### 3.2 公开证据：主动感知有效，但“朴素加相机”会崩

| 工作 | 做法 | 关键结果 | 对本轮的启示 |
|---|---|---|---|
| **ActiveAlign**（[S26]） | 先学一个 viewpoint module 生成相机轨迹；离线把轨迹终点与演示对齐、回放剩余操作、保留成功 continuation 再微调 | **朴素在 π0.5 前加相机重定位：46.3% → 11.5%**；ActiveAlign 后 π0 70.7%、π0.5 72.7%；真机遮挡 35/90 → 83/90 | **主动交互的收益取决于“训练分布是否覆盖交互后的状态”**；这是本轮最重要的风险控制点 |
| **ActiveVLA**（[S27]） | 粗到细：3D 关键区域定位 → 多视角投影 → 主动视角选择（最大化 amodal 相关性/多样性、最小化遮挡）+ 3D zoom-in | 三个仿真基准 SOTA，真机精密任务可迁移 | 视角选择可以显式优化“看清关键区域”，不需要重训大模型 |
| **SCALE**（[S28]） | 用自不确定性同时调制视觉探索与动作执行；无需额外训练/verifier，单次前向 | 仿真+真机优于 SOTA VLA 与 TTS 方法，保持单 pass | 不确定性可以作为“看哪里/怎么动”的统一信号；但它是推理策略，不解决训练分布 |
| **CheckVLA**（[S29]） | 用动作条件世界模型在执行时验证 chunk；conformal 阈值决定干预；latency-aware 前缀替换 | RoboCasa365 **36.1% vs 27.6%**（+8.5pp）；5% 误报下 timely recall **77.9% vs 48.6%**（observation-only） | 执行期验证能救“chunk 内发生偏差”；mask/谓词可以作为更便宜的动作条件信号 |
| **ActiveArena**（[S30]） | 35 个主动感知任务、5 类；可记忆标注、ID/OOD 协议；13 种 VLA 配置 | 主动感知存在显著 ID-OOD gap；记忆采样/本体/子任务监督能改善 OOD | 主动感知不是“看一眼”，是“多轮取证 + 记忆 + 决策”；评测会奖励会主动取证的策略 |

ActiveAlign 的 46.3→11.5 是全场最重要的负面证据：**不能把“加一个主动视角”当成免费增益**。相机一动，策略看到的初始状态就偏离训练分布；如果训练数据没有覆盖交互后的状态，主动感知反而会把成功率打崩。本轮因此把“post-probe alignment”写成硬约束，而不是可选技巧。

### 3.3 本轮的 delta：用 mask 不确定性触发，用任务内在探针执行

已有主动感知工作多由“任务不确定性/视角模块/世界模型”触发；本轮用**分割的 3D 不一致性**触发，因为：

- mask 熵/多视角 IoU/双目有效点比例/谓词置信度，都是**物体级**信号，比全局不确定性更接近“我看不清这个物体”。
- 触发后执行的探针必须是**任务内在**的：腕部侧视、轻推、抬起、重抓、等待传送带、开合夹爪。不是任意相机运动，也不是“问人”。
- 探针有预算：每任务 ≤2 次、总时长 ≤15s、剩余时间 <30s 时禁止；每次探针后必须重新估计 mask/谓词，并让策略知道“刚做过探针”（probe token）。
- 训练必须覆盖探针后的状态：用 ActiveAlign 式闭环对齐 + 探针增广，把“探针终点”接回演示/恢复段；否则不启用。

探针表（细节在产物区）：

| 探针 | 适用 | 信息增益 | 成本 | 风险 | 失败回退 |
|---|---|---|---|---|---|
| 腕部侧视 sweep | 遮挡/透明/边界碎 | 高 | 1–2s | 低 | 回原视角 |
| 轻推/拨开 | 干扰物遮挡、物体粘连 | 中高 | 2–4s | 中（可能移动目标） | 重新定位 |
| 抬起-and-look | 容器内/底部遮挡 | 高 | 3–5s | 中（可能掉落） | 重抓/放弃 |
| 重抓 | 抓取点错/滑移 | 高 | 3–6s | 中 | 换手/换点 |
| 等待 | 传送带/动态目标 | 高 | 1–5s | 低 | 超时回退 |
| 开合夹爪 | 物体卡住/姿态错 | 中 | 1–2s | 低 | 重新抓 |

### 3.4 主动交互不是“主策略”，是“风险预算”

如果把主动交互做成每步都调用，它会吃掉 180s 预算，并放大分布漂移。本轮把它做成三档：

```text
绿：mask 稳定、谓词置信、无干扰 → 直接执行，不探针
黄：mask 熵高/多视角不一致/谓词接近阈值 → 允许 1 次低风险探针（侧视/等待）
红：谓词失败/检测到人为干扰/透明物体深度空洞 → 允许 1 次高风险探针（轻推/抬起/重抓）+ ARM 恢复
```

这和“诊断门控”的思路相似，但触发信号从“动作/时序异常”换成了“物体级 mask 几何异常”，更贴本轮的三个词。

## 4. 三者闭环：SPD-GPR

把三个词串起来，得到一个单模型、单 checkpoint 的闭环：

```text
┌──────────────────────── Offline（教师 + 数据）────────────────────────┐
│ 33k 官方演示（4 RGB + proprio + language；无 depth/mask）              │
│   ├─ T_seg：GroundingDINO/Florence-2 + SAM2 video → 2D mask + track    │
│   ├─ T_depth：FoundationStereo（头双目）+ DepthAnythingV2（腕部）      │
│   ├─ T_pose：mask + 点云 + 对称性 → 物体/容器系；已知物体 FoundationPose│
│   ├─ T_act：更大 VLA/专家集成 → 动作速度/阶段                        │
│   ├─ 3D 抬升/多视角融合 → 物体/部件/容器 mask + 关系图                │
│   ├─ SGD：mask 合成的反事实（背景/位置/干扰/未见/人扰）               │
│   └─ PSD：多教师 on-policy 蒸馏 → 一个 student checkpoint             │
└──────────────────────────────────────────────────────────────────────┘
                                   │
┌──────────────────────── Inference（一个 checkpoint）──────────────────┐
│ language + 4 RGB + proprio                                            │
│        ▼                                                              │
│  共享 VLM backbone                                                    │
│        ├─ SMSI：2D mask + depth + 3D queries                         │
│        ├─ SPA：物体/容器系、相对位姿、对称轴                          │
│        ├─ MPV：步骤谓词、失败原因                                     │
│        ├─ APP：mask 不确定性 → 探针决策（gated）                      │
│        └─ Action expert：mask/3D token 条件化 → action chunk          │
│                                   │                                   │
│        SSG 步骤图 → 当前步骤 s_t；OPT K=1–4 位姿迁移；SVL gated 校验  │
│        ARM：谓词失败/人扰 → 恢复原语；NRB 提供官方人扰剧本            │
└──────────────────────────────────────────────────────────────────────┘
```

一句话：**SMSI 把“物体/部件/容器”变成 3D token；PSD 把这些 token 的教师能力压进一个 checkpoint；APP/ARM 只在 mask 不可信时花预算；SSG/MPV 把 token 变成步骤状态；SPA/OPT 把状态变成放置位姿；SVL 做最后厘米的闭环。**

## 5. 与第 7 轮 PILOT 的关系：保留骨架，换掉空间接口

| 关系 | 内容 |
|---|---|
| 保留 | SSG 评分步骤图、OPT 少样本位姿迁移（K 收窄到 1–4）、SVL 落点闭环（改为 gated）、NRB 官方备注恢复库、GPR-VLA/WLA 单 checkpoint、DebugLoop 平台调试回路、AH-TP/Endurance Governor/Compliance Compiler |
| 升级 | PGL 2D 锚点 → **SPA 3D mask/pose**；SVL always-on → **MPV/APP gated**；NRB 训练库 → **ARM 运行时恢复**；DebugLoop → **AxisDiagnostic 轴级诊断** |
| 新增 | **SMSI** 3D mask 空间接口、**MPV** mask 谓词验证、**PSD** 特权分割蒸馏、**APP** mask 不确定性主动探针、**ARM** 主动恢复、**SGD** mask 合成数据引擎 |
| 修剪 | ICR 26 万段、全 32 任务孪生、自由仿真/仿真 RL/运行时 MPC、每任务 LoRA、WMA-0 主路径、FLEET 第六轴 |

关键修正：第 7 轮说“终局放置是闸门、约 60% 步骤分、跨五轴杠杆”，这句话的方向仍然成立，但**理由要改**。终局放置重要的第一性原因是它是成功闸门（32/32 任务的最后一步），不是因为它占步骤分大头；步骤分只在成功率平局时用。这个修正会改变预算：不再为“把某个中间步骤从 30 分做到 40 分”投入，而是为“把完整任务从失败翻成成功”投入。

## 6. 失败模型 v2：九类失败，各自对应一个组件

| # | 失败模式 | 典型任务/轴 | 证据/机制 | 组件 |
|---|---|---|---|---|
| F1 | 物体/目标槽 grounding 错 | 位置、背景、未见物品 | 2D 外观相关；绝对坐标记忆 | SMSI + SPA + MPV |
| F2 | 透明/反光导致 mask/深度失败 | T14/T32/T10/T26 | 双目匹配失效；边界碎 | SMSI 多视角 + APP 侧视/轻推 |
| F3 | 遮挡/干扰物挡住目标 | 干扰物、背景 | 单视角 mask 缺失 | SMSI 多视角 + APP 拨开 |
| F4 | 精密放置/插入最后厘米失败 | T10/T26/T27/T19 | 深度误差 5–60mm；开环 chunk | SPA/OPT + SVL gated |
| F5 | 人为干扰 mid-task | 人为干扰 | 成功演示训练；无恢复 | MPV 变化检测 + ARM |
| F6 | 步骤状态/假完成 | 全部 | 无显式步骤状态；谓词缺失 | SSG + MPV |
| F7 | 开环 chunk 内漂移 | 动态/接触 | 批内不重规划 | MPV 每 chunk 校验 + APP/ARM |
| F8 | 抓取点错/滑移 | 未见物品、透明 | 外观偏置；部件不清 | SMSI part mask + APP 重抓 |
| F9 | 延迟/部署不稳 | 全部 | N 端口、6B + mask 头 | 部署蒸馏 + 调度 + 预算 |

这张表的作用不是“解释一切”，而是把每个组件绑到一个可测的失败模式；如果某个组件在对应失败模式上没有 ≥2pp 的增益，就砍掉（见产物区实验设计）。

## 7. 成功优先的组合分配：先翻失败，再谈步骤

### 7.1 目标函数

```text
maximize   E[1{all steps complete}]
subject to p99 latency ≤ B, probe budget ≤ 2/task, single checkpoint
tie-break  E[step score] 只在成功率相同时优化
```

由于每个 episode 值 0.3125pp，且官方一次跑只能可靠检测约 10pp，我们必须把资源集中在“能把整任务从失败翻成成功”的环节，而不是“把某步部分分提高”的环节。

### 7.2 任务分层（按失败代价 × mask 杠杆）

| 层 | 任务 | 理由 | 投入 |
|---|---|---|---|
| **Tier A** | T10 PlugCharger、T26 PlugInEthernet、T27 StackBowls、T19 ZipUp、T12 Unlock、T14 PourOutMedicine、T17 OrganizeStationery、T24 ConveyorSorting、T31 OrganizePencilCase、T32 SyringeWaterTransfer | 精密插入/堆叠/闭合/透明/人扰；mask/pose 直接对应成功谓词 | 70% 数据/训练/调试预算 |
| **Tier B** | T07 PlacePhotoFrame、T21 ArrangePlates、T25 StoreCups、T20 PaperCupStacking、T29 PackPhone、T30 RemovePinnedNote、T18 PackBag、T23 StorePaddle | 放置/闭合为主，mask 有增益但难度中等 | 20% |
| **Tier C** | 其余简单抓放/分类任务 | 主要靠基础策略；mask 边际收益低 | 10%，只做回归保护 |

### 7.3 预算分配

```text
SMSI + PSD（分割/深度/位姿蒸馏）    35%
APP + ARM（主动探针/恢复）          20%
SGD（mask 合成数据）                15%
评测/调试/统计                      15%
部署/延迟/合规                      15%
```

### 7.4 统计与决策规则

- 日常：离线 replay + 配对种子 + 分层 bootstrap；不把单任务 10 次跑当结论。
- 调试槽：每次只改一个变量；同一任务至少 10 次；记录 mask IoU/谓词 F1/成功率。
- 官方跑：预注册主终点（总成功率），次终点（5 轴成功率），探索性终点（步骤分）；用分层贝叶斯借用任务间强度。
- 停止规则：如果 Tier A 的联合增益 <3pp，或 APP 在透明/遮挡轴上 <2pp，回退到“SMSI + PSD + gated SVL”安全版。

## 8. 风险与合规（先立后破）

| 风险 | 概率 | 影响 | 缓解 | 停止条件 |
|---|---|---|---|---|
| 伪标签噪声 | 高 | 高 | 多教师一致性 + 置信过滤 + 5% 人工抽检 | mask IoU <0.7 的任务退出 PSD |

## 1. 事实核对（2026-10-26）

### 1.1 排名是成功率字典序，步骤分只是 tie-break

官方手册（[S6][S7]）原文：

```text
实时榜单按 32 个任务的总平均成功率进行排序；
成功率相同时按总平均步骤分排序；
若仍相同，则提交日期较早的模型排序靠前。
```

这条事实改变目标函数：

```text
主目标：最大化 32 任务总平均成功率
次目标：成功率打平时，最大化总平均步骤分
再次：更早提交
```

第 7 轮把“终局步骤 39.8%、放置类 59.7%”当作步骤分大头，方向仍对，但**不能把步骤分当主目标**。一个只提高中间步骤部分分、但完整任务仍失败的改动，在排名上几乎不计；一个把“第二层叠完但第三层失败”翻成“完整三层”的改动，才是 +1 episode 的真实收益。

### 1.2 320 个 episode，5 轴各 64 个，每 episode 0.3125pp

官方任务页与手册（[S1][S2][S6]）：

| 项 | 数值 |
|---|---:|
| 任务数 | 32 |
| 每任务运行次数 | 10 |
| 泛化类型 | 5（位置/干扰物/背景/未见物品/人为干扰） |
| 每类型次数 | 2 |
| 总 episode | 32×10 = **320** |
| 每轴 episode | 32×2 = **64**（20%） |
| 单次最大时长 | **180s**，超时失败 |

统计后果：

```text
每个 episode 对总成功率权重 = 1/320 = 0.3125pp
每个任务满分权重           = 10/320 = 3.125pp
总体 SE（p=0.3）           = √(0.3×0.7/320) ≈ 2.56pp
单轴 SE（n=64）            = √(0.3×0.7/64)  ≈ 5.73pp
单任务 SE（n=10）          = √(0.3×0.7/10)  ≈ 14.5pp
```

**不要用单任务 10 次跑下结论**：14.5pp 的标准误意味着 0/10 与 3/10 的差异完全可能是噪声。Tier A/B/C 的分层和配对统计不是可选项，是必需项。

## 2. 评分算术与统计功效

### 2.1 目标函数

```text
maximize   S = (1/32) Σ_t (1/10) Σ_{r=1}^{10} 1{task t run r fully succeeds}
subject to p99 latency ≤ B
           probe budget ≤ 2/task, ≤15s
           exactly one inference checkpoint
tie-break  P = (1/32) Σ_t (1/10) Σ_r step_score(t,r)
```

注意 `S` 是**32 任务平均成功率的平均**，不是 320 个 episode 的微平均；两者在本赛等价（每任务 10 次），但分层统计时按任务聚类更合理。

### 2.2 每个组件的边际价值

设某组件把任务 t 的成功率从 p_t 提到 p_t+Δ_t，且只影响 Tier A 的 |A| 个任务：

```text
ΔS = (1/32) Σ_{t∈A} Δ_t
```

如果 Tier A = 10 个任务、每个 +10pp，则 ΔS = 10/32 × 10pp = **3.1pp**。如果只影响一个任务 +10pp，则 ΔS = 0.3125pp——正好一个 episode。**这就是为什么必须按“跨任务共享的接口”设计，而不是按单任务打补丁。**

### 2.3 功效表（两比例、α=0.05、power=0.8、p≈0.3）

| 目标增益 | 每组所需 episode | 官方 320 能否检测 | 现实做法 |
|---:|---:|---|---|
| +3pp | ≈ 3,700 | 否 | 离线 replay 数千 episode + 配对；多次提交累积 |
| +5pp | ≈ 1,350 | 否 | 离线/仿真 + 1–2 次调试槽 + 分层模型 |
| +10pp | ≈ 350 | 约一次跑 | 官方跑可作确认 |
| +15pp | ≈ 170 | 是 | 官方跑可检测 |

反过来说：**320 episode 的最小可检测效应约 10–11pp**。所以：
- 不要把 2–3pp 的官方差异当结论；CI 跨 0 是常态。
- 离线实验要跑数千 episode（replay/仿真）才能对 3pp 有把握。
- 调试槽要用配对设计（同一任务、同一初始条件、A/B 交替），否则 10 次跑的标准误 14.5pp 会淹没一切。

### 2.4 分层贝叶斯读数

对 32 任务 × 5 轴的成功率建模：

```text
logit(p_{t,a}) = μ + u_t + v_a + w_{t,a}
u_t ~ N(0, σ_t²), v_a ~ N(0, σ_a²), w_{t,a} ~ N(0, σ_w²)
```

- 任务/轴随机效应借用强度，避免单任务 10 次的噪声。
- 报告后验均值 + 95% credible interval；主终点看 `μ` 或 32 任务平均。
- 预注册：主终点 = 总成功率；次终点 = 5 轴成功率；探索性 = 步骤分、mask IoU、谓词 F1。

### 2.5 步骤分的正确用法

步骤分只用于：
1. 平局时的 tie-break；
2. 诊断“失败发生在哪一步”（比成功率更有信息量）；
3. 训练辅助信号（SSG/MPV 的步骤谓词）。

**不能**用步骤分替代成功率做模型选择。一个步骤分高但成功率低的模型，在榜单上仍然输。

### 3.2 SMSI：3D 物体/部件/容器 mask 接口

#### 3.2.1 输入与输出

输入：
- 4 路 RGB：头左/头右（校正双目）、左腕/右腕。
- Proprio：双臂关节、EE base 位姿、夹爪开度、lower_body、waist。
- 语言：任务指令（5 条英文复述之一，episode 内不变）。

输出（每个物体/部件/容器）：
- `mask_2d[v]`：每视角 mask logits（1/4 分辨率）。
- `depth[v]`：每视角深度（头双目度量；腕部相对）。
- `centroid_base`：3D 中心（base 系，米）。
- `extent_base`：3D 包围盒/尺度。
- `orientation`：6D 旋转或对称轴。
- `label`：物体/部件/容器类别 + 语言 grounding 分数。
- `confidence`：mask/深度/位姿的联合置信。
- `relation`：与其他物体/容器的 `on/in/next_to/aligned/occluded` 关系。

#### 3.2.2 网络结构

```text
shared VLM backbone (WLA-1.0-Base 6B / GPR-VLA)
  ├─ vision encoder: 4 views, shared weights, per-view positional embeddings
  ├─ language encoder: instruction + step text
  ├─ spatial decoder (lightweight, 4 layers):
  │    ├─ object queries (64) + part queries (16) + container queries (16)
  │    ├─ mask head: per-view mask logits (Nq × H/4 × W/4)
  │    ├─ depth head: per-view depth (1 × H/4 × W/4)
  │    └─ 3D head: centroid/extent/orientation per query (MLP)
  ├─ relation graph: pairwise features among top-k queries → 2 layers
  ├─ predicate head: pooled mask/3D/relation → step predicates
  └─ action expert: flow-matching DiT, cross-attends to mask/3D/relation tokens
```

设计要点：
- **共享视觉编码器**：4 路视图共享权重；头双目用校正后的极线约束，腕部用 EE 位姿 + 手眼外参。
- **查询解耦**：object/part/container 三类查询分开，避免“碗口”和“碗”被同一 query 混掉。
- **mask 分辨率 1/4**：480×640 → 120×160，足够抓取/放置；腕部可内部 crop 到 240×320 再上采样。
- **mask 头周期**：默认每 4 步重算一次，中间帧用光流/EE 运动 warp 缓存；探针后立即重算。这样 6B + mask 头的 p99 可控。

#### 3.2.3 3D 抬升与多视角融合

头双目（校正后）：

```text
d = disparity (student depth head 或 teacher)
z = f · B / d
x = (u - cx) · z / fx
y = (v - cy) · z / fy
p_head = [x, y, z]
p_base = T_base_head · p_head
```

腕部单目：

```text
z_wrist = student depth (relative)
p_wrist = z_wrist · K^{-1} [u,v,1]
p_base = T_base_ee · T_ee_wrist · p_wrist
```

多视角关联：
1. 每个 query 在每视角有 mask + 3D 中心预测；
2. 用 3D 中心距离 + mask 特征余弦 + 尺度一致性构造匹配矩阵；
3. Hungarian 匹配 → 同一实例的多视角观测；
4. 融合：中心/尺度用逆方差加权；mask 用多视角投票；置信度用一致性。

关系图：
- 对每个物体，找最近的 k 个物体/容器；
- 边特征：相对位移（容器系）、法向夹角、包围盒重叠、遮挡比例、语言关系分数；
- 2 层 GNN → 关系 token，供 MPV/action expert 使用。

#### 3.2.4 透明/反光/小物体的处理

| 问题 | SMSI 处理 | 残余风险 | 回退 |
|---|---|---|---|
| 透明（T14/T32/T10） | 多视角 mask 投票；深度边缘 + 颜色梯度；腕部近景 | 双目空洞、mask 边界碎 | APP 侧视/轻推；SVL 慢速伺服 |
| 反光（金属/塑料） | 多曝光？接口不支持；用 mask 形状 + 深度 | 高光被当物体 | 只用腕部视角；阈值放宽 |
| 小物体（插头/耳塞） | 腕部 crop + 高分辨率 mask；part query | 头视角太小 | 靠近后再抓；APP 重抓 |
| 遮挡（干扰物） | 多视角 + 关系图；mask 可见部分 | 完全遮挡 | APP 拨开/抬起 |
| 未见物品 | class-agnostic mask + 形状/部件；语言 grounding | 类别混淆 | APP 多视角；试抓 |

### 3.3 SPA：mask-pose 对齐与放置/插入目标

#### 3.3.1 物体/容器系

物体系：
- 对 mask 点云做 PCA → 主轴；
- 对对称物体（碗/杯/瓶）用对称轴 + 最小惯性轴；
- 对部件（把手/插头尖端）用 part mask 的主方向；
- 对已知物体，用 FoundationPose 教师离线生成模板，学生回归。

容器系：
- 容器 mask + 内部自由空间点云；
- 开口平面法向（最小方差方向）；
- 内部中心/深度（用于“放进去”）；
- 槽位/孔位（插排/笔盒/架子）用 part/container query + 3D 位置。

#### 3.3.2 相对位姿与放置目标

```text
T_base_obj = [R_base_obj | c_base_obj]
T_base_container = [R_base_container | c_base_container]
T_container_obj = T_base_container^{-1} · T_base_obj
```

OPT 离线：

```text
对每条演示 i 的释放时刻 t_i^rel：
  H_i = T_container_obj(t_i^rel)   # 容器系下的物体释放位姿
H̄ = median_i(H_i)                 # xyz 中位数
R̄ = quaternion chordal mean       # 旋转均值
σ_xyz = std_i(H_i.xyz)
σ_θ = angular std_i(H_i.R)
```

线上：

```text
T̂_base_container = SPA(obs)
T̂_base_obj_target = T̂_base_container · H̄
```

决策：

```text
σ < τ1                 → 直接执行（快）
τ1 ≤ σ < τ2            → 慢速 + 腕部视觉伺服
σ ≥ τ2                 → 放弃迁移，退化为“mask 中心 + 保守放置”
```

插入（T10/T26）：
- 用 part mask（插头尖端、插座孔）估计轴线；
- 先对齐轴线（<2°），再沿轴慢速插入；
- 力/位混合：位置伺服 + 电流/接触阈值（若可用）；无六维力时用腕部视觉 + 小幅回退。
- 双目深度误差 15–60mm，不能直接量插入深度；用腕部近景 + mask 重叠 + EE 位移估计。

堆叠（T27）：
- 用碗口/碗底 mask 的圆/椭圆拟合；
- 对齐 XY 中心 + 碗底平面与碗口平面平行；
- 允许 ±5mm/±3° 容差；SVL 校验稳定性。

闭合（T19/T31/T17）：
- 拉链头 mask 沿齿条移动；闭合谓词 = 齿条间隙消失 + 拉链头到端点；
- 笔盒/盖子：lid mask 角度 < 阈值 + 边缘重合；
- 透明/布料：mask 边界可能碎，优先用 EE 轨迹 + 接触 + 视觉边缘。

#### 3.3.3 与 PGL 的区别

| 项 | PGL（第 7 轮） | SPA（本轮） |
|---|---|---|
| 目标表示 | 槽位 → 2D 锚点 → 6D | 物体/容器 3D mask → 相对位姿 |
| 遮挡 | 2D 锚点可能被挡 | 多视角 3D 融合 |
| 透明 | 2D 边界不稳 | 多视角 + 深度边缘 + 探针 |
| 谓词 | 2D 重叠/启发式 | 3D 关系/间隙/对齐 |
| 训练 | 渲染 overlay | mask/pose 蒸馏 + 几何 |

SPA 仍可在图像上渲染投影锚点作为辅助 prompt，但主目标是 3D 相对位姿。

### 3.4 MPV：mask 谓词验证

#### 3.4.1 谓词族

| 谓词 | 定义 | 典型任务 | 失败原因 |
|---|---|---|---|
| `grasped(obj)` | 夹爪闭合 + 物体 mask 随 EE 运动 + 接触 | 全部抓取 | 抓空/滑移/抓错 |
| `placed_on(obj, support)` | 物体底面接近支撑面 + XY 在支撑区内 + 稳定 | T27/T21/T25 | 放偏/放高/掉落 |
| `stacked(obj, base)` | 底面-顶面距离小 + XY 重叠 + 姿态对齐 + 稳定 | T27/T20 | 偏心/倾斜/滑落 |
| `inserted(part, slot)` | 尖端进入孔 + 轴线对齐 + 插入深度 + 接触 | T10/T26 | 对不准/顶住/未到底 |
| `contained(obj, container)` | 物体中心在容器内部 + 不穿模 | T17/T28/T29 | 放外/卡住 |
| `closed(lid)` | 盖角 < θ + 边缘间隙 < ε + 锁扣 | T09/T17/T19/T31 | 未合/夹物 |
| `zipped(zipper)` | 拉链头到端点 + 齿条闭合 | T19/T31 | 卡齿/未拉到底 |
| `poured(obj)` | 倾斜角 > θ + 内容物移动 | T14/T32 | 未倒/洒 |
| `sorted(obj, region)` | 物体在目标区域 + 类别匹配 | T24/T04 | 分错/放偏 |
| `removed(obj)` | 物体离开原位 + 在目标容器 | T11/T30 | 未取出/掉落 |

#### 3.4.2 阈值校准

对每个任务/步骤：
1. 在成功演示的步骤完成帧附近，计算谓词值；
2. 取 5th/95th 分位作为阈值（保守侧）；
3. 加滞回（进入阈值 vs 退出阈值差 10–20%）；
4. 用失败 replay/合成扰动校准假阳性；
5. 单任务验收：谓词 F1 ≥0.8，假完成率 ↓50%。

#### 3.4.3 步骤状态与失败诊断

```text
SSG: s_0 → s_1 → ... → s_k
MPV: p_i(t) = predicate_i(obs_t)
推进：s_t ← s_{t+1} iff p_i > θ_high for W consecutive frames
回退：s_t ← s_{t-1} iff p_i < θ_low (human disturbance / undo)
```

失败诊断映射：
- `grasped` false → `wrong_object` / `missed_grasp` / `slip`
- `placed_on` false → `wrong_target` / `too_high` / `misaligned` / `dropped`
- `inserted` false → `misaligned` / `blocked` / `insufficient_depth`
- `closed` false → `lid_blocked` / `not_engaged`
- predicate true→false → `human_disturbance`

### 3.5 PSD：多教师特权蒸馏

#### 3.5.1 教师集合

| 教师 | 输入 | 输出 | 用途 | 推理时 |
|---|---|---|---|---|
| `T_seg` | RGB + 语言/部件 prompt | 2D mask + track + 类别/部件 | mask 监督 | 否 |
| `T_depth` | 头双目 / 腕部单目 | 度量/相对深度 | 深度监督、3D 抬升 | 否 |
| `T_pose` | mask + 点云 + 模板 | 物体/容器 6D 位姿 | SPA 监督 | 否 |
| `T_act` | 观测 + 特权状态 | 动作速度/阶段 | 动作蒸馏（OPD） | 否 |
| `T_contact` | 夹爪 + mask + 轨迹 | 接触/抓取事件 | 谓词/接触监督 | 否 |
| `T_stage` | 任务步骤 + 轨迹 | 阶段/子任务标签 | SSG/MPV 监督 | 否 |

具体实现：
- `T_seg`：GroundingDINO/Florence-2 检测 + SAM2 video 跟踪；对部件用文本 prompt（“handle”“rim”“plug tip”“socket”“zipper”“lid”）。
- `T_depth`：FoundationStereo 在头双目校正图上做立体匹配；DepthAnythingV2 在腕部做单目深度，用 EE/已知尺度做尺度对齐。
- `T_pose`：已知物体用 FoundationPose；无 CAD 物体用 mask 点云 PCA + 对称性 + 类别模板；容器用开口平面/内部自由空间。
- `T_act`：用 WLA-1.0-Base 全量微调 / MolmoAct2 / π0.5 / GR00T 作为动作教师；对 flow-based 学生用速度损失（Multi-Teacher OPD）。
- `T_contact`：夹爪开合 + 物体 mask 随 EE 运动 + mask 距离；无触觉时的视觉接触代理。
- `T_stage`：官方 `score_steps` 定义阶段；用 DTW 对齐 EE 轨迹 + 谓词变化，得到阶段边界；CASD 式 chunk 对齐语义目标。

#### 3.5.2 蒸馏目标

```text
L = L_flow
  + λ_mask   L_mask      # Dice + BCE + 时序一致性
  + λ_depth  L_depth     # scale-invariant log + edge-aware smooth
  + λ_pose   L_pose      # 点匹配 + 对称感知旋转 + 中心
  + λ_rel    L_rel       # on/in/next/aligned/occluded
  + λ_pred   L_pred      # 步骤谓词 BCE
  + λ_probe  L_probe     # 探针效用/选择
  + λ_act    L_act       # 教师速度（OPD）
  + λ_feat   L_feat      # 学生空间 token vs 教师特征
```

起始权重：

| 项 | 权重 | 说明 |
|---|---:|---|
| `L_flow` | 1.0 | 主任务 |
| `L_mask` | 0.3 | 辅助 |
| `L_depth` | 0.2 | 辅助 |
| `L_pose` | 0.2 | 辅助 |
| `L_rel` | 0.1 | 辅助 |
| `L_pred` | 0.2 | 步骤状态 |
| `L_probe` | 0.1 | 只在探针数据上 |
| `L_act` | 0.5 | on-policy 阶段 |
| `L_feat` | 0.1 | 特征对齐 |

#### 3.5.3 On-policy 与 chunk 对齐

离线阶段：
- 在官方演示上监督 mask/depth/pose/predicate；
- 动作用行为克隆/flow matching。

On-policy 阶段：
- 学生在仿真/replay 中 rollout（或真实调试槽），收集学生访问的状态；
- 教师给这些状态打 mask/depth/pose/动作速度标签；
- 学生在自己的状态上学习，减少 exposure bias（Multi-Teacher OPD 的核心）。

Chunk 对齐：
- 对每个 action chunk，计算 chunk 内多个时刻的语义目标（mask/pose/阶段），加权到 chunk 条件；
- 不只是 chunk 第一帧的语义（CASD 的发现：一个 chunk 可能跨多个阶段）。

#### 3.5.4 单模型合规审计

```text
Inference graph:
  images + proprio + language
    → shared VLM backbone
    → mask/depth/pose heads (same checkpoint)
    → predicate/probe heads (same checkpoint)
    → action expert (same checkpoint)

External calls at inference: none.
Loaded checkpoints at inference: 1.
Teachers: offline only.
Deterministic geometry: back-projection, PnP/ICP, thresholding — code, not a model.
```

审计材料：
- 模型卡列出所有子模块/参数量/来源；
- 推理启动脚本只加载一个 `.pt`/`.safetensors`；
- 网络抓包/进程列表证明无外部 API；
- 教师权重不随提交分发；
- 如果评测方要求，提供“单 checkpoint 打包”的 Docker 镜像与 `get_action` 调用图。

### 3.6 APP：mask 不确定性触发的主动探针

#### 3.6.1 触发信号

| 信号 | 计算 | 阈值（起始） |
|---|---|---|
| mask 熵 | 每像素 Bernoulli 熵，物体 mask 内平均 | >0.5 |
| 多视角 IoU | 投影 mask 的 IoU | <0.5 |
| 3D 中心方差 | 多视角中心的标准差 | >2cm |
| 双目无效比例 | 低置信/无匹配像素比例 | >30% |
| mask 时序不稳 | 运动补偿后 IoU | <0.6 |
| 谓词边缘 | `|p - θ|` | <0.1 |
| 人扰检测 | 中心跳变/谓词 true→false | >5cm 或 1→0 |

#### 3.6.2 探针原语

| 原语 | 参数 | 适用 | 信息增益 | 时间 | 风险 | 回退 |
|---|---|---|---|---|---|---|
| `wrist_sweep` | 方向、角度（±20°）、速度 | 遮挡/透明/边界碎 | 高 | 1–2s | 低 | 回原视角 |
| `push` | 方向、距离（1–3cm）、速度 | 干扰物遮挡/粘连 | 中高 | 2–4s | 中 | 重新定位 |
| `lift_look` | 高度（2–5cm）、保持 | 容器内/底部 | 高 | 3–5s | 中 | 重抓/放弃 |
| `regrasp` | 预抓点、开合 | 抓取点错/滑移 | 高 | 3–6s | 中 | 换手/换点 |
| `wait` | 时长（1–5s） | 传送带/动态 | 高 | 1–5s | 低 | 超时回退 |
| `open_close` | 夹爪开合 | 卡住/姿态错 | 中 | 1–2s | 低 | 重新抓 |

#### 3.6.3 探针选择

```text
U(a) = E[ΔH(mask) | a] + α E[Δsuccess | a] - β cost(a) - γ risk(a)
```

- `E[ΔH]`：探针后 mask 熵的期望下降（用离线探针数据训练一个小的效用头）。
- `E[Δsuccess]`：探针后谓词/成功概率的期望提升（从 replay/仿真统计）。
- `cost`：时间 + 动作数。
- `risk`：碰撞/掉落/移动目标的风险（规则表）。
- 选择 `argmax U(a)`，若 `max U < θ_U` 或预算为 0，则不探针。

训练：
- 离线：在仿真/replay 中枚举探针，计算真实 `ΔH`/`Δsuccess`，训练效用头（回归/排序）。
- 真实：调试槽少量数据校准；规则兜底。

#### 3.6.4 Post-probe alignment（硬约束）

ActiveAlign 的教训：朴素加相机使 π0.5 从 46.3% 崩到 11.5%。本轮要求：

1. **数据**：对每条演示，在随机步骤插入探针，得到 post-probe 状态；用 mask/3D/EE 空间最近邻匹配回演示状态；回放剩余演示动作；保留成功 continuation。
2. **训练**：学生在这类 post-probe 状态上训练，并输入 `probe_token`（探针类型/方向/时长）。
3. **推理**：探针后必须带 `probe_token`；策略知道“刚做过什么”。
4. **验收**：无对齐的探针 vs 有对齐的探针 vs 无探针，三组对比；有对齐必须恢复无探针的 ≥80%，否则不部署。
5. **回退**：对齐失败/置信低 → 不用探针，回到保守执行或 ARM。

```python
def build_scene_masks(obs, calib, student):
```

### 4.2 谓词验证

```python
def predicate(step, inst, rel, obs):
    if step.kind == "stack":
        a, b = inst[step.obj], inst[step.base]
        return (vertical_gap(a.bottom, b.top) < TAU_Z
                and xy_overlap(a, b) > TAU_XY
                and angle(a.axis, b.axis) < TAU_ANG
                and stable(a, window=0.5))
    if step.kind == "insert":
        p, s = inst[step.part], inst[step.slot]
        return (axis_angle(p, s) < TAU_INS_ANG
                and tip_inside(p, s) > TAU_DEPTH
                and contact(obs, p, s))
    if step.kind == "place":
        o, c = inst[step.obj], inst[step.container]
        return (o.centroid_xy in c.region
                and abs(o.bottom - c.support_z) < TAU_Z
                and stable(o, window=0.5))
    if step.kind == "close":
        lid = inst[step.lid]
        return lid.angle < TAU_LID and gap(lid, inst[step.body]) < TAU_GAP
```

### 4.3 蒸馏一步

```python
def distill_step(student, teachers, batch):
    obs = batch.obs
    with torch.no_grad():
        tgt = teachers.label(obs)       # masks, depth, pose, rel, pred, velocity
    pred = student(obs)
    L = flow_loss(pred.action, batch.action)
    L += 0.3 * mask_loss(pred.mask, tgt.mask)
    L += 0.2 * depth_loss(pred.depth, tgt.depth)
    L += 0.2 * pose_loss(pred.pose, tgt.pose)
    L += 0.1 * rel_loss(pred.rel, tgt.rel)
    L += 0.2 * bce(pred.pred, tgt.pred)
    L += 0.1 * probe_loss(pred.probe, tgt.probe) if batch.has_probe else 0
    L += 0.5 * velocity_loss(pred.action, tgt.velocity)  # OPD
    L += 0.1 * cosine(pred.spatial_feat, tgt.feat)
    return L
```

### 4.4 主动探针 + 恢复

```python
def act_with_probes(obs, step, budget=2, t_left=180):
    inst, rel, masks, depth = build_scene_masks(obs, calib, student)
    u = uncertainty(inst, masks, depth, rel, step)
    if (not predicate(step, inst, rel, obs)
            and u > THETA_U and budget > 0 and t_left > 30):
        a = argmax_probe(inst, step, t_left)     # wrist_sweep/push/lift/wait...
        if safe(a, inst):
            execute(a)
            obs = observe()
            inst, rel, masks, depth = build_scene_masks(
                obs, calib, student, probe_token=a)
            budget -= 1
    if predicate(step, inst, rel, obs):
        return student.act(obs, inst, rel, step)
    return recover(inst, rel, step, obs)          # regrasp/reposition/push/rollback
```

```python
def make_probe_data(demo, probe):
```

## 8. 创新点清单（动机/差异/可行性/资源/步骤/风险/状态）

> 状态：押注=本轮主线；保留=沿用；升级=旧点改造；降级=保留但非主回路；砍=不做。

### I1 SMSI：3D 物体/部件/容器 mask 接口（新增，押注）
- 动机：数据无 depth/mask；五轴都是物体级几何变化；2D 外观模型 OOD 崩。
- 差异：不是“加一个分割模型”，而是把 object/part/container 三类 mask 抬升到 3D，作为策略的空间 token；推理时是同一 checkpoint 的内部头。
- 可行性：RAMP-3D/SG-VLA/YUBI-STAG/SEVO 证据；双目已标定；SAM2 可离线伪标签。
- 资源：mask 头 ~50M 参数；8×H100 2 周标注。
- 步骤：伪标签 → mask 头 → 3D 融合 → 关系图 → 蒸馏。
- 风险：透明/反光/小物体 → 腕部近景 + 探针；教师噪声 → 多教师一致性。

### I2 SPA：mask-pose 对齐与 3D 放置目标（新增，押注）
- 动机：2D 锚点在遮挡/透明/背景下不稳；放置/插入需要物体/容器系相对位姿。
- 差异：mask → 对称轴/开口平面/内部自由空间 → 容器系；K=1–4 演示统计。
- 可行性：双目点云 + mask + OPT；已知物体 FoundationPose 教师。
- 资源：每任务 100–300 条演示建库；2–3 天。
- 步骤：物体/容器系 → H_i 库 → 在线估计 → 执行/伺服/退化。
- 风险：无 CAD 物体位姿歧义 → 对称性 + 多视角；透明容器 → 探针/腕部。

### I3 MPV：mask 谓词验证（新增，押注）
- 动机：成功率是“所有步骤完成”；没有显式步骤状态，模型会假完成/跳步。
- 差异：把 32 任务 score_steps 翻译成 3D 谓词；谓词由 mask/3D/关系计算，可解释。
- 可行性：官方步骤文本 + mask/3D；阈值从成功演示校准。
- 资源：谓词库 32 任务；CPU/轻量头；1–2 人周。
- 步骤：谓词族 → 阈值 → 失败诊断 → 与 SSG/ARM 接线。
- 风险：谓词噪声 → 滞回 + 多信号；透明/布料 → 视觉边缘/EE 轨迹兜底。

### I4 PSD：多教师特权蒸馏（新增，押注）
- 动机：单模型规则禁止在线教师；数据无 mask/depth；需要把空间能力压进一个 checkpoint。
- 差异：蒸馏的是 3D mask/pose/contact/谓词，不只是动作；on-policy 学生状态；chunk 对齐。
- 可行性：Multi-Teacher OPD/VLA-AD/Shallow-π/PFD/DreamMimic/CASD 证据。
- 资源：教师离线；8×H100 2–3 周。
- 步骤：离线 → on-policy → chunk 对齐 → 部署蒸馏。
- 风险：教师噪声/分布漂移 → 一致性过滤 + 学生状态标注。

### I5 APP：mask 不确定性主动探针（新增，押注）
- 动机：透明/遮挡/人扰是 passive mask 的盲区；主动交互能补，但朴素加相机会崩。
- 差异：用 mask 熵/多视角不一致/谓词边缘触发；任务内在探针；post-probe 对齐硬约束。
- 可行性：ActiveAlign/ActiveVLA/SCALE/CheckVLA/ActiveArena 证据。
- 资源：探针数据 3–5k episodes；调试槽校准。
- 步骤：不确定性 → 探针库 → 效用头 → 对齐数据 → 部署。
- 风险：分布漂移/时间开销 → 对齐 + 预算 + 回退。

### I6 ARM：主动恢复管理（新增）
- 动机：人为干扰轴是官方明确条件；成功演示没有恢复数据。
- 差异：官方 human 备注 → 恢复剧本；MPV 触发；恢复原语库。
- 可行性：备注公开；2.5D 合成/回放便宜。
- 资源：3,200 恢复对；1 人周。
- 步骤：剧本 → 数据 → 策略 → 预算/安全。
- 风险：备注编号含义未核实 → 同时覆盖随机扰动。

### I7 SGD：mask 合成数据引擎（新增）
- 动机：五轴需要多样性；官方数据背景/位置有限；全孪生太贵。
- 差异：用 mask/深度层做 2.5D 合成，不用全物理仿真；真实:合成 ≥6:4。
- 可行性：SAM2 mask + 深度 + 泊松融合；10–20k episodes。
- 资源：2–3 人周；GPU 标注。
- 步骤：背景 → 位置 → 干扰 → 未见 → 人扰 → 质量门。
- 风险：伪影/物理不合理 → 拒绝率 + 人工抽检 + 只用感知/grounding。

### I8 SSG：评分步骤图（保留）
- 官方 score_steps → 状态机；MPV 提供谓词；语言 grounding。

### I9 OPT：少样本放置位姿迁移（保留，收窄）
- K=1–4；容器系由 SPA 估计；σ 驱动伺服；不做轨迹复制。

### I10 SVL：落点闭环（升级为 gated）
- 只在 MPV 低置信/高价值步骤触发；≤2 次；缓放 + 稳定校验 + nudge/regrasp。

### I11 NRB：官方备注恢复库（保留）
- human_1/human_4 剧本 → 破坏/恢复对；训练 ARM/可逆信念。

### I12 GPR-VLA/WLA：单 checkpoint 主干（保留）
- 6B，LoRA，ee 动作空间，chunk 4–8；承接 mask/3D token。

### I13 AxisDiagnostic：32×5 轴级诊断（新增）
- 每任务×轴的成功率/mask IoU/谓词 F1/失败原因；指导 Tier A/B/C 和训练。

### I14 部署蒸馏：Shallow-π/VLA-AD 式压缩（新增，可选）
- 如果 p99 超标：层蒸馏/语义蒸馏/量化；目标 ≤200ms（stretch 150ms）。

### I15 DebugLoop + 功效感知评测（保留，升级）
- 调试槽只改一个变量；同任务 ≥10 次；预注册；分层贝叶斯；不把 2–3pp 噪声当结论。

### 已砍清单
- ICR 26 万段检索；全 32 任务高保真孪生；自由仿真/仿真 RL/运行时 MPC；每任务 LoRA/模型合并；WMA-0 主路径；FLEET 第六轴。

## 9. 风险、合规与开关

| 风险 | 概率 | 影响 | 缓解 | 停止条件 |
|---|---|---|---|---|
| 伪标签噪声 | 高 | 高 | 多教师一致性 + 置信过滤 + 5% 人工抽检 | mask IoU <0.7 的任务退出 PSD |
| 单模型审计 | 中 | 高 | 一个 checkpoint；教师离线；模型卡逐项披露 | 审计不过 → 去掉独立 mask 头，退回辅助损失 |
| 延迟超标 | 中 | 高 | mask 头 1/4 频率；量化；层蒸馏 | p99 >250ms → 关 mask 头或降分辨率 |
| 探针分布漂移 | 高 | 高 | post-probe 对齐 + probe token + 回退 | 无对齐时成功率下降 → 不启用 APP |
| 透明/反光 | 高 | 中 | 腕部侧视 + 轻推 + 多视角；不硬做双目 | 深度空洞率 >50% → 只用 2D/边缘 |
| 人为干扰 | 中 | 高 | 官方备注剧本 + 随机扰动 + ARM | 恢复成功率 <50% → 只保留回滚 |
| 统计噪声 | 高 | 中 | 320 episode + 配对 + 分层模型 | CI 跨 0 → 不上线 |
| 外部数据/合作违规 | 低 | 高 | 默认 OFF；邮件确认后再开 | 明确禁止 → 只用官方数据 |
| 探针安全 | 中 | 高 | 力/位/碰撞约束；只允许白名单原语 | 触发安全阈值 → 立即回退 |
| 相机标定不一致 | 中 | 高 | 调试槽重投影/视差检查；在线自标定兜底 | 重投影 >5px → 关双目，只用单目/腕部 |
| 腕部外参未知 | 中 | 中 | 离线手眼标定；EE 相对深度 | 外参误差 >1cm → 不用腕部 3D，只用 2D crop |
| 合成数据伪影 | 中 | 中 | 质量门 + 真实:合成 ≥6:4 | 真实 held-out 下降 → 降合成比例 |
