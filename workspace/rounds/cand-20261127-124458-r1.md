# 第 4 轮（新一轮灵感循环第 1 轮；承接第 3 轮 KT-MPC / KTCG；本轮灵感：「痛点分析」×「动作分块」）

> **基线**：第 3 轮 v28（KEMPC ∪ IEKC ∪ CTKTP ∪ AKWA = KT-MPC；九证一体 KTCG；IP-462~466；定义 1500–1599）。
> 本轮纪律：**只做增量，不放宽安全合取**。痛点分析升级「注意力分配轴」，动作分块升级「时间承诺轴」；任一组件失效都必须能一键退回 v28 的逐步 KT-MPC。降级链：PAC-MPC ⇒ KT-MPC ⇒ KEMPC。

## 0. 直觉与动机

**灵感 1（痛点分析 → 从「全时域均匀安全」到「按决策相关性分诊」）**

直觉：第 3 轮的 KTCG 是一个「全时域合取门」：只要 horizon 内任意一步违反任意一条 KC，整个计划就被拒绝。这有两个隐性代价。第一是**过度保守**：真正危险的往往只是几个关键窗口（脚跟着地、脚尖离地、步态切换、地形边缘、外力冲击后），而大量平稳步被同一条严格规则一起卡死。第二是**注意力摊薄**：验证预算、解释预算、求解预算在 H 步上均匀铺开，导致最该被仔细检查的高风险窗口反而采样不足。

痛点分析提供的不是「放水」，而是**分诊**：用「严重度 × 频度 × 决策耦合 × 不可逆性」给每个时间窗口打分，把有限的验证与解释预算优先投给「知道了会改变动作、且错了就回不来」的窗口。关键纪律与第 3 轮一脉相承：**痛点只改注意力和顺序，不改安全合取**。一个 `dec=0`（知道与否都不改变任何下游决策）的盲区，痛点恒为 0；一个高频但可完全恢复的小扰动，也不应与一次不可逆的踏空同权。

**灵感 2（动作分块 → 从「滚动一步执行」到「带承诺的可中断动作块」）**

直觉：MPC 其实已经算出了 H 步动作序列，但执行时只走第一步就重算。动作分块把这个序列切成若干块，并**承诺执行整块**（open-loop chunk），到块尾或触发中断才重规划。好处很直接：步态相位内的动作更平滑、抖动更少、重规划频率更低、算力更省。代价也同样直接：块内没有反馈，世界一旦在块中途变化，机器人会被「锁」在旧动作上，反应被延迟到块尾。

因此分块不能只是「少算几次」，必须配一个**承诺证书**：证明在扰动管内，整块执行后仍落在安全集内，并且块内任意一步都存在一条不超过 `K_rec` 步的逃生/恢复动作。没有逃生集的块，再省算力也不能承诺。动作分块的本质不是「把时间变长」，而是「用可证明的可恢复性去换取更长的开环承诺」。

**灵感 3（两者耦合 → 痛点决定「块多长、查多细」，分块决定「痛在哪、证书发到哪一级」）**

直觉：痛点和分块是同一枚硬币的两面。痛点是**资源分配信号**，分块是**承诺的时间单元**。自然的设计是：高痛窗口 → 短块 + 紧证书 + 多验证样本 + 快中断；低痛窗口 → 长块 + 松验证 + 少样本 + 平滑执行。反过来，分块也改变了痛点的度量单位：痛点不再是「某一步」的属性，而是「某一块」的属性，因为块才是承诺和证书的最小单位。

二者耦合后形成一个闭环：痛点 → 块长/预算 → 执行与监测 → 实现痛点 → 账本校准 → 下一轮痛点。核心风险也在这里：**痛点乘了频度，稀有但灾难性的事件会被系统性地打成低痛，从而被分到长块**，而长块恰恰是 open-loop 承诺最危险的地方。

## 1. 研究问题（本轮要回答什么）

- **Q1（痛点的可测性）**：块级痛点能否定义为可观测、可证伪、且与下游决策损失相关的量？它会不会退化成「违规次数」这类虚荣指标？
- **Q2（分块的增益与代价）**：带承诺证书的动作分块，相比逐步滚动，能省多少重规划/算力、提升多少平滑性？承诺带来的反应延迟能否被中断机制压住？
- **Q3（耦合的失稳）**：当痛点驱动块长时，是否会把「稀有高风险块」误判为长块，造成承诺盲区？痛点账本能否在线检出这种系统性低估？

## 2. 设计原则（雏形，正式化见产物区定义 1600–1608）

**P1 分诊只分配（Triage-Only Allocation）**
痛点分数只能改变块长、验证样本数、解释粒度与执行顺序，不能放宽 KTCG 的任何一条安全合取；最终准入仍是全时域合取。形式化方向：`feasible(PAC(Π)) = feasible(Π)`，其中 PAC 只重排/重分块，不新增动作。

**P2 承诺必须有逃生（Commitment Requires Escape）**
任何被 open-loop 执行的块，必须在块内每一步都存在恢复动作，且恢复时间 ≤ `K_rec`；否则该块必须被切成更短的块，或退回逐步执行。逃生集为空 = 承诺无效。

**P3 痛点必须可校准（Pain Must Be Auditable）**
记录「预测痛点 vs 实现痛点」（实际违规、近失事件、恢复代价、实际决策改变），用账本持续校准痛点泛函；禁止用痛点分数本身作为优化目标（防 Goodhart）。校准误差超界时，自动缩短 `K_max` 并抬高维护地板 `f_min`。

**P4 安全优先于省算力（Safety-First Efficiency）**
分块带来的算力节省只能来自低痛、可承诺的窗口；一旦 CCC 失效、状态离开扰动管或中断条件触发，立即退回 v28 的逐步 KT-MPC。省算力永远不能以扩大承诺盲区为代价。

## 3. 形式化目标（增量 v29）

1. 定义动作块与分块算子 𝒞，块长 `K_j`，块边界与步态相位/关键事件对齐。
2. 定义块级痛点泛函 `Pain(C_j) = sev_j · freq_j · dec_j · (irr_j + λ_rec(1−irr_j))` 及稳健下界 `Pain_LB`。
3. 定义痛点自适应块长 `K_j = clamp(K_min, K_max, g(Pain_LB(C_j)))`，并受反应时上界 `K_react` 约束。
4. 定义块承诺证书 `CCC(C_j) = (B_j, A_j, ρ_j)`：扰动可达集、块内逃生集、承诺裕度。
5. 定义块级知识门 CLKG：逐块验证 KC，并要求块间边界交接证书；全计划通过 ⟺ 所有块通过且边界不变式成立。
6. 定义痛点加权验证分配 PWVA：固定预算 `B_ver` 下按 Pain 密度分配样本，带维护地板 `f_min`。
7. 定义 PAC-MPC 执行器与中断条件；证明 `Exec_v29 ⊆ Exec_v28`。
8. 定义痛点账本与校准误差指标，给出稀有事件漏检率 `κ_hit` 的上界与自适应收紧规则。

**本轮最大风险（一句话）**：**承诺盲区对稀有灾难事件的系统性低估**——痛点泛函乘了频度，稀有但不可逆的事件会被判成低痛并被分到长块，而长块正是 open-loop 承诺最不可逆的地方；系统会在绝大多数时间里又快又稳，直到某一次「低痛长块」里发生无法在块内恢复的滑移或踏空。

## 2. 形式化定义（要点）

### 定义 1600（动作块与分块算子 𝒞）

给定 horizon `[0,H)` 上的控制序列 `u_{0:H−1}`，一个分块是划分
`0 = τ_1 < τ_2 < … < τ_{M+1} = H`，第 j 块为
`C_j = ([τ_j, τ_{j+1}), u_{τ_j:τ_{j+1}−1})`，长度 `K_j = τ_{j+1} − τ_j`。

分块算子 `𝒞: (x_0, π, φ, Pain) ↦ {C_j}` 必须满足：

1. **覆盖性**：`∪_j [τ_j, τ_{j+1}) = [0,H)`，块间不重叠。
2. **相位纯度**：若相位 `φ` 在 `[τ_j, τ_{j+1})` 内恒定，则称该块为相位纯块；跨相位边界的块必须显式标记为 transition 块，并额外携带相位切换证书。
3. **长度界**：`K_min ≤ K_j ≤ K_max`。
4. **痛点单调性**：在相同相位/事件类型下，若 `Pain_LB(C_j) ≥ Pain_LB(C_k)`，则 `K_j ≤ K_k`（高痛 ⇒ 短块）。
5. **反应时约束**：`K_j ≤ K_react(Pain_LB(C_j))`，其中 `K_react(p)·dt ≤ τ_react_max(p)`，高痛对应更短的最大反应延迟。

> 直觉：分块不是把时间随便切段，而是把「同一承诺语义 + 同一证书粒度」的时间段放在一起；跨相位硬切会破坏接触连续性，因此必须单独出证。

### 定义 1601（块级痛点泛函 Pain）

对块 `C_j`，记 `sev_j` 为块内最坏违规的归一化后果（如 CoM 越出支撑多边形的最大裕度损失、预测跌倒概率、接触力越界比例），`freq_j` 为触发事件在块内的经验/模型频率（如每步脚跟着地次数、地形切换次数、外力冲击到达率），`dec_j` 为「解析该块不确定性后下游决策效用的期望改变」归一化值，`irr_j` 为块内不可恢复状态的比例。定义

```
Pain(C_j) = sev_j · freq_j · dec_j · (irr_j + λ_rec · (1 − irr_j))
Pain_LB(C_j) = max(0, Pain(C_j) − z_β · σ_Pain(C_j))
```

其中 `σ_Pain` 为痛点估计不确定度，`z_β` 为置信分位（如 1.64 对应 95%）。排序一律用 `Pain_LB`，避免对高不确定痛点过度乐观。

关键性质：

- `dec_j = 0`（知道与否都不改变任何动作）⇒ `Pain = 0`，这是「虚荣验证」的过滤器；
- `irr_j = 1`（不可恢复）⇒ 痛点不打折；`irr_j = 0`（完全可恢复）⇒ 只保留 `λ_rec` 的残余代价，不会被高频小扰动淹没；
- `freq_j` 是双刃剑：稀有事件天然低痛，这正是本轮最大风险的来源，需由账本（定义 1607）与维护地板（定义 1605）共同兜底。

### 定义 1602（痛点自适应块长）

令

```
K_target(p) = clamp(K_min, K_max, round(κ / (p + ε)))
K_j = min(K_target(Pain_LB(C_j)), K_react(Pain_LB(C_j)), phase_remaining(τ_j))
```

其中 `κ > 0` 为尺度常数，`ε > 0` 防除零，`phase_remaining` 保证不跨相位硬切（跨相位时插入一个显式 transition 块）。`K_react(p) = floor(τ_react_max(p) / dt)`，且 `τ_react_max` 关于 p 单调递减。

> 直觉：高痛块必须短到「即使块内没有反馈，也能在可接受延迟内重规划」；低痛块可以长到「一次承诺换更多平滑与算力」。`K_react` 是硬约束，防止痛点映射把高风险块拉长。

### 定义 1603（块承诺证书 CCC）

给定块初态 `x_{τ_j}`、开环控制 `u_{τ_j:τ_{j+1}−1}`、有界扰动集 `W`，定义扰动前向可达集

```
B_j(τ_j) = {x_{τ_j}}
B_j(k+1) = F(B_j(k), u_k) ⊕ W,   k = τ_j, …, τ_{j+1}−1
```

安全不变集 `S_safe` 与块内逃生集

```
A_j(k) = { a ∈ U^{≤K_rec} : ∀x ∈ B_j(k), F^{≤K_rec}(x, a) ⊆ S_safe }
ρ_j = min_{k∈C_j} dist(B_j(k), ∂S_safe)
```

块承诺证书 `CCC(C_j) = (B_j, A_j, ρ_j)` 成立，当且仅当：

1. **鲁棒安全**：`∀k∈C_j, B_j(k) ⊆ S_safe`；
2. **处处可逃**：`∀k∈C_j, A_j(k) ≠ ∅`；
3. **承诺裕度**：`ρ_j ≥ ρ_min`。

> 直觉：条件 (1) 保证「整块执行也不会进入危险区」；条件 (2) 保证「即使中途要反悔，每一步都还有退路」；条件 (3) 保证退路不是贴着边界。三者缺一不可——只有 (1) 而没有 (2)，等于「安全但不可中断」；只有 (2) 而没有 (1)，等于「能逃但已经太晚」。

### 定义 1604（块级知识门 CLKG）

对每个块 `C_j` 与其中的每条激活 KC `c_i`，在扰动管 `B_j` 上做鲁棒裕度检验：

```
m_i(B_j) = min_{k∈C_j} min_{x∈B_j(k)} m_i(x)
```

其中 `m_i(x)` 为第 3 轮定义的有符号规则裕度（`m_i ≥ 0` 表示规则成立）。块通过当且仅当 `∀i, m_i(B_j) ≥ 0`。

全计划通过当且仅当：

1. 所有块通过；
2. 每个边界 `τ_{j+1}` 的交接证书 `H_{j→j+1}` 成立：`B_j(τ_{j+1})` 被下一块的初态假设集包含，且共享约束（接触连续性、CoM 速度连续性、相位一致性）满足。

> 与 v28 的关系：v28 是「逐名义步」检查 KC；CLKG 是「逐块在扰动管上」检查 KC，再额外加边界交接。由于 `B_j(k)` 包含名义轨迹点，CLKG 通过 ⇒ 名义轨迹每步都通过 v28 的 KC 检查。因此 `Exec_v29 ⊆ Exec_v28`（引理 26）。

### 定义 1605（痛点加权验证分配 PWVA）

给定总验证预算 `B_ver` 与块级下界 `Pain_LB(C_j)`，分配

```
b_j = max( f_min · B_ver / M ,  B_ver · Pain_LB(C_j) / Σ_k Pain_LB(C_k) )
```

若地板项导致总和超过预算，则对超出部分按 `Pain_LB` 比例回缩（带地板的注水解）。样本数 `n_j = floor(b_j / c_sample)`，求解精度/解释粒度同理按 `b_j` 分档。

> 直觉：把预算按「痛感密度」分配，等价于在固定预算下最大化期望痛点下降；维护地板 `f_min` 则是对「稀有事件低痛」这一盲区的强制保险——再低的痛也要留一份审计样本。

### 定义 1606（PAC-MPC 执行器与中断）

每次重规划：

1. 调 KT-MPC 求完整计划 `π`；
2. CPA 计算 `PainField`；
3. PACO 生成块划分 `{C_j}`；
4. PWVA 分配验证预算；
5. 对每个块计算 `B_j`、`CCC(C_j)`、`CLKG(C_j)`；
6. 若某块失败：先尝试**只修该块**（收紧约束/缩短块长后重优化）；仍失败则拒绝整计划，退回 v28；
7. 执行第一个块，逐步监测中断条件：
   - 扰动估计超出 `W`；
   - 实际状态离开 `B_j`；
   - `A_j(k)` 变空（逃生丢失）；
   - 当前块 `Pain_LB` 超过高痛阈值；
   - 高严重度事件检测器触发（滑移、冲击、地形突变、接触丢失）；
8. 中断时在最近的安全步用 `A_j` 逃生，然后重规划。

> 关键：**块级修复不等于块级放行**。修复只允许把失败块变得更保守或更短；最终执行仍要求所有块与所有边界都通过。这样既保留了「高痛块快速重规划」的效率，又不破坏 v28 的安全合取。

### 定义 1607（痛点账本与在线校准）

对每个块记录二元组：

```
(predicted) = (sev, freq, dec, irr, Pain, Pain_LB)
(realized)  = (violations, near_misses, recovery_cost, decision_change)
```

定义校准误差与稀有事件漏检率：

```
ε_pain = E[ |Pain_pred − Pain_realized| ] / Pain_max
κ_hit  = P( Pain_realized ≥ θ_high | Pain_pred < θ_low )
```

在线用保序回归 / conformal 校准更新 `sev/freq/dec/irr` 的映射；若 `κ_hit > κ_max`，自动执行：

1. 收紧 `K_max ← max(K_min, floor(α·K_max))`；
2. 抬高维护地板 `f_min ← min(1, f_min + Δf)`；
3. 对「低痛但高不可逆」的块强制附加审计样本（不参与常规预算竞争）；
4. 若仍超界，禁用低痛长块，退回较短的统一分块。

> 直觉：痛点本身是一个估计量，必须像第 3 轮的 μ_i 一样接受回测。账本的作用不是让痛点更「好看」，而是让「预测低痛、实际高痛」这种系统性偏差无处藏身。

### 定义 1608（v29 执行集）

```
Exec_v29 = { π ∈ Exec_v28 : ∃ 分块 𝒞(π) 使得
             ∀C_j: CCC(C_j) ∧ CLKG(C_j) ∧ 边界 H_{j→j+1} 成立 }
```

由于条件是在 `Exec_v28` 之上追加的合取，`Exec_v29 ⊆ Exec_v28`。

class ChunkPainAnalyzer:
    """把计划切成候选块，并按 sev×freq×dec×irr 计算块级痛点。"""

    def __init__(self, severity_model, frequency_model,
                 decision_model, irreversibility_model,
                 z_beta: float = 1.64, lambda_rec: float = 0.1):
        self.severity_model = severity_model
        self.frequency_model = frequency_model
        self.decision_model = decision_model
        self.irreversibility_model = irreversibility_model
        self.z_beta = z_beta
        self.lambda_rec = lambda_rec

    def analyze(self, x0, plan, phase, kc_list, terrain) -> list[ChunkPain]:
        out = []
        for (a, b) in self._candidate_chunks(plan, phase):
            sev = max(self.severity_model(x0, plan, k, kc_list, terrain)
                      for k in range(a, b))

            dec = self.decision_model(plan, a, b, kc_list)
            irr = self.irreversibility_model(x0, plan, a, b)

            pain_lb = max(0.0, pain - self.z_beta * sigma)
            out.append(ChunkPain((a, b), sev, freq, dec, irr,
                                 pain, pain_lb, sigma))
        return out

class ChunkCommitmentCertifier:
    """证明 open-loop 块在扰动下安全，且每一步都有逃生动作。"""

    def __init__(self, dynamics, disturbance_set, safe_set,
                 k_rec: int = 10, rho_min: float = 0.0):

        self.W = disturbance_set
        self.S_safe = safe_set

### IP-470 Chunk-Level Knowledge Gate (CLKG)

```python
class ChunkLevelKnowledgeGate:
    """逐块在扰动管上验证 KC，并要求边界交接。"""

    def __init__(self, kc_list, margin_fn, handoff_checker):
        self.kc_list = kc_list
        self.margin_fn = margin_fn
        self.handoff_checker = handoff_checker

    def check_chunk(self, chunk, tube):
        worst = {}
        for kc in self.kc_list:
            if not getattr(kc, "is_active", True):
                continue
            m = min(self.margin_fn(kc, x)
                    for states in tube.values() for x in states)
            if m < 0:
                return False, kc.name, m
            worst[kc.name] = m
        return True, None, worst

    def check_plan(self, chunks, tubes, boundaries):
        for c, t in zip(chunks, tubes):
            ok, name, m = self.check_chunk(c, t)
            if not ok:
                return False, f"chunk_{c}_violates_{name}_margin_{m}"
        for (prev, nxt) in boundaries:
            if not self.handoff_checker(prev, nxt):
                return False, "boundary_handoff_failed"
        return True, "ok"
```

### IP-471 Pain-Weighted Verification Allocator (PWVA)

```python
class PainWeightedVerificationAllocator:
    """固定预算下按痛点密度分配验证资源，并保留维护地板。"""

    def __init__(self, budget: float, f_min: float = 0.1):
        self.budget = budget
        self.f_min = f_min

    def allocate(self, pain_field: list[ChunkPain]) -> list[float]:
        m = len(pain_field)
        total = sum(max(p.pain_lb, 1e-9) for p in pain_field)
        floor = self.f_min * self.budget / m
        raw = [max(floor, self.budget * max(p.pain_lb, 1e-9) / total)
               for p in pain_field]
        # 地板可能使总和超预算：对超出部分按 pain_lb 比例回缩
        if sum(raw) > self.budget:
            excess = sum(raw) - self.budget
            weights = [max(p.pain_lb, 1e-9) for p in pain_field]
            wsum = sum(weights)
            raw = [b - excess * w / wsum for b, w in zip(raw, weights)]
        return raw
```

@dataclass
class PainAdaptiveChunkedMPC:
    """KT-MPC 的痛点自适应分块执行层。"""
    base: KnowledgeTransilientMPC
    cpa: ChunkPainAnalyzer
    paco: PainAdaptiveChunkingOperator
    ccc: ChunkCommitmentCertifier
    clkg: ChunkLevelKnowledgeGate
    pwva: PainWeightedVerificationAllocator
    ledger: "PainLedger"

        pain = self.cpa.analyze(x0, plan, phase,
                                self.base.kc_list, terrain)
        chunks = self.paco.chunk(pain, phase, self.base.horizon)
        alloc = self.pwva.allocate(pain)

        tubes, certs = [], []
        for c, b in zip(chunks, alloc):
            # 预算 b 控制采样/区间精度；低预算用更粗的包络但更保守的 W

### IP-474 Pain Ledger (PL)

```python
class PainLedger:
    """预测痛点 vs 实现痛点，在线校准并触发保守收紧。"""

    def __init__(self, kappa_max: float = 0.05):
        self.records = []
        self.kappa_max = kappa_max
        self.k_max_scale = 1.0
        self.f_min_bonus = 0.0

    def log(self, chunk, predicted, realized):
        self.records.append((chunk, predicted, realized))

    def calibration_error(self) -> float:
        if not self.records:
            return 0.0
        return sum(abs(p.pain - r.cost) for _, p, r in self.records) \
               / (len(self.records) * PAIN_MAX)

    def rare_event_miss_rate(self) -> float:
        low = [(p, r) for _, p, r in self.records if p.pain_lb < THETA_LOW]
        if not low:
            return 0.0
        return sum(1 for _, r in low if r.cost >= THETA_HIGH) / len(low)

    def update_policy(self):
        if self.rare_event_miss_rate() > self.kappa_max:
            self.k_max_scale = max(0.25, self.k_max_scale * 0.8)
            self.f_min_bonus = min(0.4, self.f_min_bonus + 0.05)
```

### IP-473 Pain-Adaptive Chunked Cert Gate (PAC-CG)

```python
@dataclass
class PainAdaptiveChunkedCertGate:
    """十证一体：在 KTCG 之上追加 CCC / CLKG / PWVA 的联合准入。"""
    ktcg: KnowledgeTransilientCertificationGate
    ccc: ChunkCommitmentCertifier
    clkg: ChunkLevelKnowledgeGate
    pwva: PainWeightedVerificationAllocator

    def admits(self, plan, chunks, tubes, certs) -> bool:
        # 1) 原有九证（结构/语义/动力学/可解释/迁移/权重/知识库/DCC/一致性）
        if not self.ktcg.admits(plan.robot_plan, plan.sensor_data):
            return False
        # 2) 每块承诺证书
        if not all(c.valid for c in certs):
            return False
        # 3) 每块知识门 + 边界交接
        ok, _ = self.clkg.check_plan(
            chunks, tubes, list(zip(chunks[:-1], chunks[1:])))
        if not ok:
            return False
        # 4) 验证预算合规（不得低于维护地板）
        alloc = self.pwva.allocate(plan.pain_field)
        if any(b < self.pwva.f_min * self.pwva.budget / len(alloc)
               for b in alloc):
            return False
        return True
```

## 4. 复杂度分析（增量更新）

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 |
|---|---|---|---|
| CPA 痛点分析 | `O(H · (C_sev + C_freq + C_dec + C_irr))` | `O(M)` | H≤40, M≤20；严重度/不可逆模型为主要开销 |
| PACO 分块 | `O(H log H)` | `O(M)` | 相位切分 + 按痛点递归切分 |
| CCC 可达集 | `O(H · n_x² · n_w)`（区间/多面体） | `O(H · |B|)` | `n_w` 为扰动维数；粗包络可降为 `O(H·n_x)` |
| CLKG 逐块验证 | `O(H · N_rule · n_x)` | `O(N_rule)` | N_rule≤50；Lipschitz 裕度可线性化 |
| PWVA 分配 | `O(M log M)` | `O(M)` | M≤20 |
| PAC-MPC 单步 | `O(N·n_x³)`（KT-MPC 主导）+ `O(H·N_rule·n_x)` | `O(N·n_x + M·|B|)` | 分块验证开销相对 KT-MPC <15% |
| 执行节省 | 重规划频率 ↓ `≈ 1/E[K_j]` | — | 低痛段 `K_j` 可接近 `K_max` |

**实时性**：KT-MPC 求解仍是主瓶颈（N=20, n_x=12, n_u=6 时 5–15ms）。CCC 若用区间算术 + 预计算包络，单块 <1ms，M≤10 时 <10ms；CLKG 逐块鲁棒裕度 <2ms；CPA/PACO/PWVA 合计 <2ms。因此单次重规划仍可压在 20–30ms 内。真正的实时收益来自**执行期**：低痛段一次承诺 `K_j` 步，重规划次数降到原来的 `1/E[K_j]`，平均算力显著下降；高痛段保持短块，不牺牲反应速度。若 CCC 无法在预算内算出，则 `K=1` 退回 v28，不阻塞控制。

## 5. 正确性论证（增量更新）

### 引理 26（块级门对 v28 的单调精化）

**陈述**：若计划 `π` 通过 CLKG（所有块在扰动管上满足所有激活 KC，且边界交接成立），则 `π` 也通过 v28 的逐名义步 KC 检查。因此 `Exec_v29 ⊆ Exec_v28`。

**证明**：对任意块 `C_j` 与任意名义步 `k∈C_j`，名义状态 `x_k^nom ∈ B_j(k)`（可达集包含名义轨迹）。CLKG 要求 `min_{x∈B_j(k)} m_i(x) ≥ 0`，故 `m_i(x_k^nom) ≥ 0`，即该步满足 KC `c_i`。对所有块、所有步、所有激活 KC 成立，故 `π` 满足 v28 的逐 step 合取。边界交接是额外约束，只会进一步缩小集合。∎

### 引理 27（块承诺的安全性）

**陈述**：若 `CCC(C_j)` 成立，块从 `x_{τ_j} ∈ B_j(τ_j)` 开始执行，且实际扰动 `w_k ∈ W`，则对所有 `k∈C_j`，实际状态 `x_k ∈ B_j(k) ⊆ S_safe`。

**证明**：对 k 归纳。基例 `x_{τ_j} ∈ B_j(τ_j)` 由初态假设。归纳步：`x_{k+1} = F(x_k, u_k) + w_k ∈ F(B_j(k), u_k) ⊕ W = B_j(k+1)`（归纳假设 `x_k∈B_j(k)` 与 `w_k∈W`）。由 CCC 条件 (1)，`B_j(k+1) ⊆ S_safe`。∎

### 引理 28（中断可恢复性）

**陈述**：若在块内第 k 步触发中断，且 `CCC(C_j)` 成立，则存在长度 `≤K_rec` 的逃生动作序列，使状态在扰动仍属于 `W` 时回到 `S_safe`。

**证明**：CCC 条件 (2) 给出 `A_j(k) ≠ ∅`，即存在 `a ∈ U^{≤K_rec}` 使 `∀x∈B_j(k), F^{≤K_rec}(x,a) ⊆ S_safe`。实际状态 `x_k ∈ B_j(k)`（引理 27），故执行 `a` 即可在 `K_rec` 步内回到 `S_safe`。∎

### 引理 29（痛点预算分配的注水解最优性）

**陈述**：在不考虑地板时，分配 `b_j ∝ Pain_LB(C_j)` 最大化 `Σ_j Pain_LB(C_j) · h(b_j)`（`h` 为凹的验证收益函数）的线性化目标；加入地板 `f_min` 后，PWVA 给出带下界约束的注水解（KKT 条件成立）。

**证明**：目标对 `b_j` 的边际收益为 `Pain_LB(C_j) · h'(b_j)`。最优时各块边际收益相等（除非触地板）。PWVA 先按 `Pain_LB` 比例分配，再对触地板块固定 `f_min`、其余按比例回缩，正是带下界约束的水注水过程。∎

### 定理（PAC-MPC 的安全保持）

**陈述**：在以下条件下，PAC-MPC 执行的实际状态不会越过 v28 的安全保证：(i) 每个被执行的块都满足 `CCC`；(ii) 全计划通过 `CLKG` 与边界交接；(iii) 中断条件至少每步检查一次；(iv) 任一块失败时退回 v28 逐步执行。

**证明**：由 (ii) 与引理 26，计划属于 `Exec_v28`。由 (i) 与引理 27，块内实际状态始终在 `S_safe`。若中断发生，由引理 28 可在 `K_rec` 内逃生；若无法修复/出证，由 (iv) 退回 v28，其安全性已在第 3 轮证明。故 PAC-MPC 的安全性不弱于 v28。∎

### 定理（痛点-反应时约束）

**陈述**：若块 `C_j` 的 `Pain_LB ≥ p`，则 `K_j ≤ K_react(p)`，从而最坏反应延迟 `≤ K_react(p)·dt ≤ τ_react_max(p)`。

**证明**：由定义 1602 的 `K_j = min(…, K_react(Pain_LB(C_j)), …)` 直接得到。∎

### 定理（稀有事件漏检的可控性）

**陈述**：在账本校准下，若经验漏检率 `κ_hit ≤ κ_max`，则「预测低痛、实际高痛」的块出现概率不超过 `κ_max`；当 `κ_hit > κ_max` 时，`K_max` 收缩与 `f_min` 抬升会单调降低每块的暴露时长与低痛块的审计缺口，从而降低后续漏检概率。

**证明**：`κ_hit` 的定义即为条件概率 `P(realized ≥ θ_high | predicted < θ_low)`。`K_max` 收缩降低单块暴露时长，`f_min` 抬升增加低痛块样本，二者都只能减少（或不变）漏检机会；审计样本为强制项，不参与预算竞争。∎

> 注意：这是**概率性**保证，不是绝对安全保证；它依赖可交换性/分布稳定假设，而新地形、新负载恰恰可能破坏该假设。这正是本轮最大风险的来源。

## 6. 实验设计

| 编号 | 目的 | 设置 | 指标 |
|---|---|---|---|
| E1 | 痛点校准 | 离线日志 + 仿真回放，覆盖平地/台阶/碎石/湿滑 | `ε_pain`、`κ_hit`、可靠性图 |
| E2 | 分块效率 | 同一 KT-MPC 计划，比较逐步 vs 均匀分块 vs PAC | 重规划频率、CPU/步、jerk、跟踪误差 |
| E3 | 安全性 | 地形切换、外力冲击、负载突变 | 违规率、跌倒率、最大 CoM 越界、恢复成功率 |

## 8. 退化链与接口（如何退回 v28）

- CPA 不可用 / 痛点不可信 ⇒ 均匀痛点 ⇒ 均匀分块（固定 `K`），仍可执行；
- PACO 不可用 / 相位未知 ⇒ `K=1`，等价 v28 逐步 KT-MPC；
- CCC 不可计算 / 逃生集为空 ⇒ 禁止 open-loop 承诺，`K=1` 退回 v28；
- CLKG 任一块失败且修复失败 ⇒ 拒绝整计划，退回 v28；
- PWVA 不可用 ⇒ 均匀预算，仅失去效率收益；
- 账本不可用 ⇒ 使用保守 `κ_max` 与更短 `K_max`；
- 任何新组件异常 ⇒ 捕获异常并退回 v28，绝不让分块层成为单点故障。

## 9. 本轮最大风险（最终确认）

**一句话**：**承诺盲区对稀有灾难事件的系统性低估**——痛点泛函乘了频度，稀有但不可逆的事件会被判成低痛并被分到长块，而长块正是 open-loop 承诺最不可逆的地方；系统会在绝大多数时间里又快又稳，直到某一次「低痛长块」里发生无法在块内恢复的滑移或踏空，且这种失败比逐步执行更隐蔽，因为它把「反应延迟」藏进了「平滑高效」的表象里。
