# 第 43 轮（新灵感循环第 1 轮） · 证书下沉到底盘：执行能力包络 × 证书时效 × 证书感知实时调度（四层架构 v8，补上 L0 执行层）

> 承接第 42 轮 v19（Sim-Cert-RAG 飞轮）。上一轮把证书做成了「可进化的资产」，但它始终悬在决策/规划层：CAR 的守卫、LCS 的边际、CMC 的监控，都隐含一个从未被证明的假设——**底盘能在控制周期内按规划给出的 (v, ω, a) 精确执行，且证书在整个动作执行期间保持新鲜**。本轮灵感词「嵌入式系统」「移动底盘」正好戳破这个假设：移动底盘有滑移、电机饱和、电池压降、热降额、编码器量化、CAN 延迟；嵌入式系统的实时调度与 WCET 决定证书能否在截止期前算出、能否在动作期间保持有效。因此本轮不新增「更上层」的智能，而是把证书栈**向下补上第 0 层**：底盘执行证书（ACE）× 证书时效（timing）× 证书感知实时调度（schedulability），并给出它与上层证书的**垂直组合定理**。

## 0. 直觉与动机

**灵感 1（移动底盘 → 证书的「执行地基」）**：第 42 轮之前的证书都假设「指令即事实」：规划器说以 1.2 m/s 转弯，CAR 就认为车体真的以 1.2 m/s 转弯。但差速/滑移转向底盘的真实映射是**轮速 → 地面力 → 滑移 → 车体速度**，中间隔着摩擦、载荷转移、轮胎侧偏、电机扭矩饱和与电池压降。直觉上，证书需要一层「物理可行性证书」：在当前电池电压、电机温度、载荷、摩擦与滑移估计下，**哪些 (v, ω, a) 是底盘真能兑现的**。我们把这个集合叫**执行能力包络 ACE**。ACE 不是策略，而是证书的「地基」——上层可以规划任何轨迹，但只有落在 ACE 里的指令才配谈安全边际。

**灵感 2（嵌入式系统 → 证书的「时间维度」）**：证书不仅有空间有效域，还有**时间有效期**。感知、融合、监控、规划、控制跑在一组嵌入式任务上，监控器的 WCET 与响应时间决定了「证书什么时候算得完」，控制周期与总线延迟决定了「证书什么时候过期」。第 42 轮的 T_hold 只回答「保持多久安全」，没回答「在这段时间里监控器还来不来得及再看一眼」。本轮引入**证书时效 T_valid** 与**证书感知实时调度**：把监控器当作最高关键度任务，用响应时间分析（RTA）证明它在执行器截止期前完成；一旦错过截止期或证书超龄，直接判证书失效并落到 SafeStop——**宁可不走，也不拿过期证书走**。

**灵感 3（垂直组合 → 证书的「全栈闭合」）**：有了 ACE 与时效，就能把「规划层证书」与「执行层证书」缝起来：若上层要求边际 m ≥ θ 且持续 T_hold，底层保证指令 u ∈ ACE 且跟踪误差 ≤ e_track、证书年龄 ≤ T_valid，则物理状态的等效边际 m_eff = m − L_m·e_track 仍 ≥ θ'。这条**垂直组合定理**把第 42 轮「仿真→知识→边缘」的横向飞轮，补成「底盘→融合→自动机→知识」的纵向全栈闭合。移动底盘还带来一个新耦合：**能量-热降额**会让 ACE 随电量/温度收缩，因此自动机必须**预测性预迁移**到低功耗模式，而不是等到 ACE 缩到不够用才急停。

**一句话直觉**：以前证书是「地图上的安全走廊」，本轮要证明「走廊脚下的地板（底盘）真的承重，而且地板不会在你走到一半时塌（时效/降额）」。

## 1. 形式化定义（增量：定义 38–43）

**定义 38（底盘执行能力包络 ACE）**：设底盘工况 c = (V_batt, T_motor, m_payload, μ̂, ŝ)，其中 μ̂ 为摩擦估计、ŝ 为滑移估计；状态 x 下的执行能力包络定义为
A(x, c) = { u = (v, ω, a) : ∃ τ_l, τ_r，|τ_l|, |τ_r| ≤ ρ(c)·τ_max(c)，且 (τ_l, τ_r) = Φ⁻¹(v, ω, a; μ̂, ŝ) 满足摩擦锥与侧偏约束，且跟踪误差 e_track(u, c) ≤ e_max }。
ρ(c) ∈ (0, 1] 为能量-热降额系数。工程上 A 用离线多保真模型（电机热模型 + 电池等效电路 + 滑移模型）预计算成按 c 分桶的只读表，在线 O(log N) 查表 + 插值。

**定义 39（滑移耦合的跟踪误差界）**：差速/滑移转向底盘的轮速命令到车体速度存在滑移映射 M(μ, s)。定义横向与纵向跟踪误差上界
e_lat ≤ κ_s · ŝ · L_wb · T_turn，e_lon ≤ ½·κ_a·|a|·Δt_ctrl²，
e_track = √(e_lat² + e_lon²)。
**滑移膨胀边际**：m_eff(x) = m(x) − L_m · e_track(x)；即底盘打滑直接吃掉上层证书的安全边际。

**定义 40（垂直证书组合定理）**：若在动作时域 [t, t+T_hold] 内同时满足：(1) 上层证书给出 m(x_t) ≥ θ；(2) 规划指令 u_t ∈ A(x_t, c_t)；(3) 实际跟踪误差 ≤ e_track；(4) 证书年龄 age_t ≤ T_valid；则物理状态满足 m_eff(x_t) ≥ θ − L_m·e_track ≥ θ'，即端到端安全不变式成立。证明由三角不等式与不变式归纳给出：ACE 保证执行可行，跟踪误差界把指令空间的不变式搬到物理状态，时效保证所依据的状态估计未过期。

**定义 41（证书时效 T_valid）**：T_valid(x) = min( T_hold(x), D_act − R_monitor − C_monitor − J_max, T_fresh )，其中 D_act 为执行器命令截止期，R_monitor 为监控任务响应时间，C_monitor 为 WCET，J_max 为最坏抖动，T_fresh 为状态估计新鲜度上界。若证书年龄 age > T_valid，则判定证书过期，强制单调降级到 SafeStop。

**定义 42（证书感知实时调度 / 时间证书）**：任务集 Γ = {τ_percept, τ_fuse, τ_monitor, τ_plan, τ_ctrl}，τ_monitor 为最高关键度。固定优先级下响应时间 R_i = C_i + Σ_{j∈hp(i)} ⌈R_i/T_j⌉·C_j。**时间证书**成立当且仅当 R_monitor + C_ctrl ≤ D_act 且所有高关键度任务可调度；否则空间边际再大，证书也判无效（timing-certificate invalid）。混合关键度用 AMC：低关键度任务在监控器超载时被降级/丢弃，保监控器。

**定义 43（能量-热降额与预测性预迁移）**：降额函数 ρ(V, T) 对温度单调不增、对电压在阈值以下单调不减。定义功率余量 m_pow(t) = |A(x, c_t)| − |A_required(x)|，其变化率 ṁ_pow。当 ṁ_pow < −ρ̇_thresh 或 m_pow < m_pow_min 时，自动机在执行能力仍够用时**提前**触发 PowerPreempt 迁移到低功耗模式，避免 ACE 突然塌缩导致的急停抖动。

## 2. 新增与升级 IP 设计

### 2.1 IP-57 CHASSIS-EXEC-CERT（底盘执行证书 CEC）
1. **ACE 离线建模**：电机热模型（铜损/铁损/温升）、电池等效电路（OCV-SoC-R_int）、滑移-摩擦模型；按 (V_batt, T_motor, m_payload, μ̂, ŝ) 分桶预计算 ACE 表与 τ_max 降额曲面。
2. **在线联合观测器**：递推最小二乘/EKF 估计 μ̂、ŝ 与电池内阻；输出带保守上界的估计，供 ACE 选桶时取**悲观桶**（下界电压、上界温度、下界摩擦）。
3. **跟踪误差界标定**：对底层速度/扭矩闭环做阶跃、正弦、打滑工况辨识，拟合 κ_s、κ_a，给出 e_track 的保守包络，用区间算术核验闭环 Lyapunov 条件。
4. **降额预迁移接口**：向自动机暴露 ρ、dρ/dt 与 m_pow，触发 PowerPreempt。

### 2.2 IP-58 CERT-TIMING-SCHEDULER（证书感知实时调度 CTS）
1. **WCET 分析**：监控器用静态分析 + 测量混合定界；对 L0 查表与 INT8 推理给出带 cache/总线争用的 WCET 上界。
2. **混合关键度调度**：监控器固定最高优先级，规划/感知可降级；AMC 模式切换时冻结证书并进入 hold-safe。
3. **证书时效运行时**：每个证书对象携带 (T_valid, deadline, epoch)；控制回路每拍检查 age ≤ T_valid，超龄立即 SafeStop。
4. **截止期错过检测**：硬件看门狗 + 心跳；监控器错过截止期等价于证书失效，不等待上层确认。

### 2.3 IP-59 CHASSIS-CERT CO-DESIGN（底盘-证书共设计工具链 CCC）
1. **资源预算分配**：给定底盘参数与证书规格，自动求 ACE 表分辨率、监控器周期/优先级、MCU/SoC 卸载位置，使时间证书成立且资源最省。
2. **证书预算（certificate budget）**：把 CPU 时间、RAM、CAN 带宽、功耗按证书关键度分配，输出可审计的资源账本。
3. **最大安全能力反解**：在保证 m_eff ≥ θ 的前提下反解最大 v/ω/a，给出「能跑多快」的证书化上界。
4. **一键部署清单**：schema + 校验器 + 版本哈希，接入 IP-53 的蒸馏导出后端。

## 5. 本轮最大风险

**一句话**：执行层证书把「底盘模型」当成了新的可信根——ACE 依赖滑移/摩擦/电池的在线估计，而恰恰在低摩擦、低电量、电机饱和这些最需要保证的极端工况下，观测器最容易失准、模型最容易外推失效，于是上层会拿到一个「看起来合法」的包络，在物理层被静默突破；因此 E87（ACE 覆盖召回）与 E88（滑移膨胀界）必须作为红线实验，任何一项不达标即降速+收紧 e_max 回退。

## 2. 关键算法（伪代码）

### IP-57 CEC：ACE 计算、跟踪误差与降额观测
```
def compute_ace(x, c):
    rho = derating(V=c.V_batt, T=c.T_motor)          # 0..1
    tau_max = rho * motor_torque_limit(c.V_batt)
    A = []
    for (v, w, a) in candidate_grid(x):
        tau_l, tau_r = inverse_dynamics(v, w, a,
                          mu=c.mu_hat, slip=c.slip_hat)
        if max(abs(tau_l), abs(tau_r)) <= tau_max \
           and friction_cone_ok(tau_l, tau_r, c.mu_hat) \
           and track_error_bound(v, w, a, c) <= E_MAX:
            A.append((v, w, a))
    return A, rho

def track_error_bound(v, w, a, c):
    e_lat = K_SLIP * c.slip_hat * L_WB * turn_time(w)
    e_lon = 0.5 * K_ACC * abs(a) * DT_CTRL**2
    return sqrt(e_lat**2 + e_lon**2)

def observe_chassis(u, meas):
    # 递推最小二乘 / 对角 EKF：估摩擦、滑移、电池内阻
    c.mu_hat  = rls_update(mu_model, u, meas.accel)
    c.slip_hat = ekf_slip_update(u, meas.wheel_speed, meas.body_speed)
    c.V_batt  = meas.bus_voltage
    c.T_motor = meas.motor_temp
    # 悲观取值：ACE 选桶时用下界电压、上界温度、下界摩擦
    return pessimistic_bucket(c)

def derating(V, T):
    rho_T = clip(1.0 - K_T * max(0, T - T_NOM), RHO_MIN, 1.0)
    rho_V = clip(1.0 - K_V * max(0, V_LOW - V), RHO_MIN, 1.0)
    return min(rho_T, rho_V)
```

### IP-58 CTS：时间证书、证书时效与截止期看门狗
```
def response_time_analysis(taskset):
    # 固定优先级，高优先级先算
    for tau in sorted_by_priority(taskset, reverse=True):
        R = tau.C
        while True:
            interference = sum(ceil(R / j.T) * j.C
                               for j in taskset if j.prio > tau.prio)
            R_new = tau.C + interference
            if R_new == R:
                break
            R = R_new
            if R > tau.D:
                return INVALID('deadline miss', tau)
        if R > tau.D:
            return INVALID('deadline miss', tau)
    return VALID

def timing_certificate(taskset, D_act):
    # 监控器最高关键度；混合关键度下低关键度可降级
    if not response_time_analysis(taskset): return INVALID
    mon = taskset['monitor']
    return VALID if (mon.R + taskset['ctrl'].C <= D_act) else INVALID

def cert_tick(cert, dt, D_act, R_mon, C_mon, J_max):
    cert.age += dt
    T_valid = min(cert.T_hold,
                  D_act - R_mon - C_mon - J_max,
                  cert.T_fresh)
    if T_valid < 0 or cert.age > T_valid:
        return degrade_to_safestop('cert_expired')
    return OK
```

### IP-59 CCC：垂直组合、包络可加性与预迁移
```
def composed_certificate(x, u, cert_up, ace, timing):
    if u not in ace.A:
        return Reject('outside_ACE')
    if not timing.valid or cert_up.age > timing.T_valid:
        return SafeStop('stale_or_untimed')
    e = track_error_bound(*u, ace.c)
    m_eff = cert_up.m - cert_up.L_m * e
    ok = (m_eff >= cert_up.theta_star)
    return Accept(m_eff) if ok else Degrade('margin_below_theta')

def envelope_additivity(skills, ace):
    # 并发技能共享底盘：资源/能力需求不可简单相加时须显式检查
    demand = sum(skill.required_envelope for skill in skills)
    return demand <= ace.A      # 向量化比较：逐 (v,w,a) 维度

def power_preempt(ace_now, ace_req, drho_dt, m_pow, rho_dot_thr, m_pow_min):
    if drho_dt < -rho_dot_thr or m_pow < m_pow_min:
        return car.request_transition('PowerPreempt')
    return None

def ccc_budget(chassis_params, cert_spec):
    # 自动分配：ACE 表分辨率 / 监控器周期优先级 / MCU-SoC 卸载
    plan = solve_resource_allocation(chassis_params, cert_spec,
             objs=['cpu_util<0.7', 'timing_certificate_valid',
                   'safety_margin_max'])
    plan.max_safe_speed = invert_margin(plan, theta=cert_spec.theta)
    plan.deploy_pkg = {
        'ace_table': plan.ace_table,
        'task_set': plan.taskset,
        'theta_star': plan.theta_star,
        'cert_hash': hash(plan.ace_table, plan.taskset)
    }
    return plan
```

def car_transition_guard(e, x, cert, ace, clock):

def certify_light_v3(x, guards, ace, budget_us=210):

## 5. 风险与缓解（增量）

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| ACE 模型在低摩擦/低电量/饱和极端工况外推失效 | 高 | 悲观选桶 + 在线估计误差界；E87 红线；越界即降速 |
| WCET 低估或调度分析过于乐观，导致证书实际超龄 | 高 | 混合静态/测量定界 + 余量系数；E89/E90 红线；看门狗兜底 |

| 跟踪误差界标定外推不足（新地面/载荷） | 中-高 | 在线残差监控，超界自动增大 e_track 并重标定 |
| PowerPreempt 与上层模式切换抖动 | 中 | 冷却期 + 滞回 + EWMA；最小触发间隔硬约束 |
| 并发技能包络可加性假设不成立（底盘耦合非线性） | 中 | 强制显式可加性检查；不通过则串行化 |
| 共设计工具链过度工程化、无人使用 | 中 | 先做 CLI + 三种参考底盘模板；E93 以「2 小时可部署」验收 |

## 6. 本轮最大风险

**一句话**：执行层证书把「底盘模型」当成了新的可信根——ACE 依赖滑移/摩擦/电池的在线估计，而恰恰在低摩擦、低电量、电机饱和这些最需要保证的极端工况下，观测器最容易失准、模型最容易外推失效，于是上层会拿到一个「看起来合法」的包络，在物理层被静默突破；因此 E87（ACE 覆盖召回）与 E88（滑移膨胀界）必须作为红线实验，任何一项不达标即降速+收紧 e_max 回退。
