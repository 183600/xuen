## 0. 本轮一句话：把常识从“知识”编译成“可执行的关系约束”

第 1 轮把失败归因于“抓握状态不可观测”，于是去学一个抓握隐变量。本轮换一个更根本的归因：**模型不是不知道物体长什么样，而是不知道物体之间“应该怎样发生关系”**。插网线、开锁、拧瓶盖、拉拉链、插针、取电池——难的不是像素，而是“塞进去 / 旋开 / 抽出来”这些**关系谓词**。常识推理的价值不在于让 VLM 多答对几道物理题，而在于把这些关系**编译成动作空间里的软 / 硬约束**；分布外泛化的价值不在于让特征更鲁棒，而在于这些关系在 5 类官方偏移下**保持不变**。两者是同一枚硬币：**常识是 OOD 的可迁移核**。

---

## 1. 直觉（先不给公式）

### 画面 1 · 最难的 6 个任务，难在“关系”，不在“像素”

teaser 榜最差的是 Plug In Ethernet 17.7、Unlock 20.1、Spell robot 21.8、Organize Stationery 22.5、Open Pill Bottle 22.7、Pick Out Battery 23.3。把它们排在一起看：插网线（公母配合 + 卡扣）、开锁（钥匙插入 + 旋转）、拼字（细粒度支撑）、整理文具（包容）、开药瓶（下压 + 旋转）、取电池（从腔体中抽出）。**没有一个是在考“看清物体”，全都在考“物体与物体 / 腔体 / 关节的关系”**。VLA 把观测直接映射到动作，跳过了这层关系表示；训练分布内可以靠轨迹记忆蒙混，分布外就原形毕露。

### 画面 2 · 5 类泛化场景改的是“外观 / 位置”，不改“物理关系”

位置偏移改坐标，干扰物改场景里多了谁，背景改纹理，未见物品改形状 / 材质，人为干扰改动态主体。**但“杯子要正着放才能装水”“网线要按下卡扣才能插”“瓶盖要逆时针旋”“插头要对准孔轴”这些关系，在五个轴上全都不变。** 这就是为什么 commonsense 是 OOD 的正确抽象层：它把“见过的像素”换成“不变的约束”。

### 画面 3 · 大模型的常识是“声明式”的，机器人要的是“程序式”的

问 VLM“怎么开这个药瓶”，它能答“先下压再逆时针旋转”；但这句话不能直接变成 7 维关节轨迹。**声明式常识 → 程序式约束**之间有一道鸿沟：谓词对了，动作未必对；谓词错了，动作会自信地错。本轮的全部工程，就是修这座桥：**关系图（看得见）→ 约束编译器（说得出）→ 验证器 / 候选选择（做得到）**。

## 2. 把常识形式化：四类关系原语

直觉上“常识”包罗万象，工程上必须收敛到可观测、可编译、可验证的最小集合。我们把 32 个任务需要的物理常识压成四族（严格定义见产物区 U13–U24）：

| 关系族 | 谓词（示例） | 编译成什么动作约束 | 典型任务 | 主要 OOD 轴 |
|---|---|---|---|---|
| **S 支撑 / 堆叠 / 悬挂** | `support(o1,o2)`, `stable(o)`, `on(o1,o2)`, `hanging(o,hook)` | 接近方向、释放高度、堆叠轴、重心投影、悬挂对位 | Stack Cups、Hang the Cup、Spell robot | 位置、未见物品 |
| **C 包容 / 遮挡** | `in(o,c)`, `contains(c,o)`, `occludes(o1,o2)`, `open(c)` | 从开口上方进入、避障走廊、目标可见性、非目标不动 | Organize Stationery、Toolbox、Pack Bag | 干扰物、背景 |
| **A/M 关节 / 装配** | `articulates(o,axis)`, `rotates`, `inserts(p,h)`, `mates`, `latches` | 运动基元（螺旋 / 直插 / 下压）、轴对齐、力 / 速度上限、卡扣确认 | Unlock、Plug In Ethernet、Zip Up、Syringe | 未见物品、位置 |
| **D/H 稳定 / 安全** | `fragile(o)`, `deformable(o)`, `non_destruction`, `human_occupied(region)` | 夹持宽度 / 速度上限、禁区、让行 / 急停 | Fold Towel、人为干扰 | 全部 |

**关键区分**：这不是“affordance 检测”的换皮。Affordance 是**物体中心**的（“这个杯子可抓”）；常识关系是**关系中心**的（“这个杯子的把手要套进那个钩子”“这根针要沿这个轴进入那个瓶口”）。32 个任务里真正卡住模型的是后者。

## 3. 量化动机（本轮本地探针，可复现）

用 `exp/commonsense_ood/cs_relation_probe.py` 把 32 任务按上述原语编码，在 teaser 榜的 8×32 个点上检验“关系负载是否解释成功率分层”。主分析用**单标签**（每任务只取最主要关系，避免多标签带来的循环论证），多标签作稳健性检查。

**结果（单标签，置换检验 50k 次）**：

| 组 | n | 平均成功率 | 其余任务 | 差值 | p |
|---|---|---|---|---|---|
| A（关节 / 旋转） | 3 | 22.07 | 25.50 | **−3.42** | **0.035** |
| M∪A（装配 / 关节） | 8 | 23.03 | 25.89 | **−2.87** | **0.006** |
| M∪A∪D（再加可变形） | 9 | 23.14 | 25.97 | **−2.83** | **0.005** |
| P（纯抓放） | 5 | 27.29 | 24.78 | **+2.51** | **0.049** |
| C（包容） | 12 | 25.47 | 25.00 | +0.47 | 0.635 |
| S（支撑 / 堆叠） | 6 | 25.87 | 25.01 | +0.86 | 0.479 |

多标签口径方向一致但更弱：M∪A 差 −2.33（p=0.022），P 差 +2.93（p=0.008）。关系负载（去掉 P 后的原语数）与成功率 r=−0.284（p=0.112）。

**读法**：真正显著的是 **A/M（关节 / 装配）显著更难、P（纯抓放）显著更易**；C/S 不显著。这与“断点在最后对齐 / 插入 / 释放”的第 1 轮结论互相印证，并把“最后一环”进一步定位到**关系表示**，而不是笼统的“控制精度”。

**必须声明的局限**：①单标注、规则编码，存在主观性；②teaser 是占位表，不是官方终稿；③n=32、多重比较，p 值只能作方向性证据；④相关性 ≠ 因果，真正的因果验证靠 E619–E623。**本轮不拿这些数字调参，只拿它们决定“火力往哪投”。**

## 4. 研究问题（轮次版）

- **Q1（关系可观测性）**：在 4 路 RGB + 1 维夹爪 + EE 位姿的观测下，能否稳定抽出 S/C/A/M 四类关系，并在**未见物体**上保持校准（而不是只记住训练物体）？
- **Q2（声明式→程序式鸿沟）**：VLM 的关系判断准确率，能在多大比例上转化为“可执行且不伤害”的约束？谓词对但动作错的比例有多高？这是本轮最关键的未知量。
- **Q3（验证器引导）**：在不改权重、不加接口的前提下，用常识验证器对 K 个候选 chunk 做 best-of-N，能否把 OOD 成功率抬起来？延迟代价多少？K 的最优值是多少？
- **Q4（不变性）**：哪些关系在 5 类官方偏移下真的不变？哪些会漂移（例如未见物体的“可抓”判断）？如何检测漂移并降级？
- **Q5（合规）**：关系图、验证器、best-of-N 都发生在推理侧，是否仍满足“单 checkpoint / 单 API / 不读评测侧信息”？如何自证？

---

## 5. 设计原则

- **P1 关系优先于外观**：策略条件化的最小充分统计量是“关系图 + 物体中心特征”，不是整帧纹理。外观进入策略的唯一合法通道是“用于估计关系”，不是“用于记忆场景”。
- **P2 软约束优先**：常识约束默认是软惩罚 / 候选排序；只有“置信度 > τ 且违反会造成不可逆伤害”时才升为硬约束（do-no-harm）。
- **P3 声明式与程序式分开验收**：谓词准确率、约束可执行率、端到端成功率是三个不同指标，不能互相替代（对应 L12）。
- **P4 推理期计算换泛化**：best-of-N 只在相位不确定时开启，K 与延迟预算绑定；默认 K=1，可回退。
- **P5 不变量可证伪**：每条关系都要预注册“在哪个 OOD 轴上会失效”的假设；不能证伪的关系不进主线。
- **P6 合规单模型**：不训练 per-task 策略、不读测试标签、不调用外部在线服务；所有“专家”必须在同一 checkpoint 内。

## 0. 本轮结论摘要

**一句话路线**：把常识编译成关系约束，把关系约束当作 OOD 的不变核，用验证器在推理期做候选选择。

**三层栈 + 两个支撑层**：

1. **关系层（CSG）**：从多视角观测抽出 support / containment / articulation / mating + 不确定性。
2. **编译层（CAC）**：把关系谓词编译成动作空间的软 / 硬约束与运动基元。
3. **验证层（CV + BoN）**：对 K 个候选 chunk 做常识验证，选最不违反约束、最可能推进终态的那个。
4. **数据层（CODA）**：按 5 轴生成反事实场景与“常识硬负例”，补足 OOD 覆盖。
5. **表示层（CIR）**：常识不变性正则，压掉与关系无关的外观捷径。

**为什么是这三层（四条证据）**：

| 证据 | 数值 | 推出的设计 |
|---|---|---|
| A/M 任务显著更难 | 单标签：M∪A 23.03 vs 25.89，−2.87，p=0.006 | 关系层直击断点 |
| 纯抓放任务显著更易 | P 27.29 vs 24.78，+2.51，p=0.049 | “关系”而非“抓取”是分水岭 |
| 第 1 轮：终态成功唯一、专长准正交、断点在最后 | `step ≈ 1.337·succ + 0.09`；oracle +4.26；最难任务集中插入 / 旋转 | 编译层与验证层对准终态 |
| 5 类 OOD 轴改外观不改关系 | 位置 / 干扰物 / 背景 / 未见物品 / 人为干扰 | 关系层是 OOD 的可迁移核 |

**合规红线**：单 checkpoint、单 API；best-of-N 是推理期计算，不训练 per-task 策略；不读评测侧信息；不调用外部在线服务；所有约束可审计、可回退。

## 2. 创新点详述

### IP-09 · CSG 常识场景图（P0）

- **动机**：本轮探针显示 A/M（关节 / 装配）任务显著更难（23.03 vs 25.89，p=0.006），而纯抓放更易（27.29 vs 24.78，p=0.049）。这说明瓶颈不是“看见物体”，而是“表示物体之间的关系”。VLA 的端到端映射没有显式的关系槽位，分布内靠轨迹记忆、分布外就失去结构。
- **与现有方案的差异**：目标检测给框和类；affordance 模型给物体中心的可操作分数；场景图工作多用于导航 / 问答。CSG 的输出是**任务可执行的关系**：支撑面、包容腔体、关节轴、公母配合、卡扣、可达性、稳定性，且每条边带**校准后的置信度**。它不是“更细的感知”，而是“策略可条件化的最小关系结构”。
- **技术可行性**：中–高。①冻结 VLM（Qwen3-VL / Molmo 级）零样本给出关系候选；②几何探针用头部双目做深度、腕部相机做近距验证、EE 位姿提供米制尺度；③官方 32 个 LeRobot 数据集可用 state/action 自动伪标关系（夹爪闭合 + 物体随动 → grasp；物体进入容器包围盒 → containment；动作下关节角持续变化而末端不动 → articulation；插入后位姿不再沿轴前进 → latched）；④小头（ViT-S / ResNet18）蒸馏 VLM，满足延迟。
- **所需资源**：数据 = 官方 32 数据集；算力 = 1×A100 数小时（伪标 + 小头训练），VLM 仅离线打标 / 低频在线；接口 = 纯策略内部，不新增字段。
- **落地步骤**：①定义关系本体与 DSL（U13–U16）；②用 state/action 自动伪标 + 人工抽检 5%；③VLM 零样本基线；④蒸馏小头 + 温度校准；⑤按“留出物体 / 背景 / 位置 / 干扰物”做 OOD 切分；⑥只在相位边界或不确定时调用（默认每 4–8 步一次），缓存上一帧关系图。
- **风险**：①关系伪标噪声（缓解：多源交叉 + 校准 + 抽检）；②VLM 幻觉（缓解：高精度门控，见 IP-10/L11）；③双目深度在透明 / 反光物体上失效（缓解：腕部近距 + EE 位姿 + 单目先验）；④延迟（缓解：低频调用 + 小头 + 缓存）。

### IP-10 · CAC 常识动作编译器（P0）

- **动机**：大模型的常识是**声明式**的（“逆时针旋开”），机器人要的是**程序式**的（7 维关节 / EE 轨迹 + 夹爪时序）。这道鸿沟是本轮最大的技术未知量（Q2 / L12）。不修这座桥，CSG 只是一个好看的图。
- **与现有方案的差异**：LLM 规划器输出文本子目标；VLA 输出动作块；CAC 输出的是**带类型的约束程序**：接近向量、避障走廊、运动基元（螺旋 / 直插 / 下压 / 钩 / 推 / 倾倒）、速度 / 力代理上限、终止谓词（卡扣到位 / 旋到限位 / 物体随动）。约束是**可检查、可回退、可审计**的。
- **技术可行性**：中–高。关系本体是固定的四族，编译器可以规则化：`insert(p,h) → 轴对齐 + 直插 + 接触后小步搜索`；`articulates(o,axis) → 绕轴螺旋 + 力矩代理上限`；`contains(c,o) → 从开口上方进入 + 走廊避障`；`support(o,s) → 垂直下放 + 释放高度`。未见关系用 LLM 生成 DSL，再做 schema 校验与几何可行性检查。
- **所需资源**：算力 = 小（规则 + 小模型）；数据 = 官方数据拟合基元参数（轴、间隙、速度）；接口 = 无。
- **落地步骤**：①定义约束 DSL（类型 / 子空间 / 边界 / 软硬 / 置信度）；②为 S/C/A/M 手写编译器；③用官方数据拟合每个基元的参数分布；④LLM 兜底编译器 + schema 校验；⑤运行时每相位编译一次，不每步编译；⑥接 IP-11 的验证器做闭环。
- **风险**：①编译器 bug（缓解：单元测试 + 回放数据自检）；②轴 / 间隙估计错（缓解：多帧一致性 + 接触后搜索）；③约束过紧压死策略（缓解：默认软约束 + 只在不可逆伤害时硬化，见 L10）；④LLM 生成非法 DSL（缓解：schema + 几何可行性双校验，失败即回退规则版）。

### IP-11 · CV-BoN 验证器引导的候选选择（P0）

- **动机**：OOD 失败往往在“常识上明显不对”（撞到容器壁、夹爪没对准、物体没被夹住、插入方向反了）。一个便宜的常识验证器就能在这些候选里挑出更合理的那个；而本赛制允许推理期计算，且不改权重、不改接口，是**合规红利**。
- **与现有方案的差异**：LLM 的 best-of-N 用奖励模型选文本；机器人常见做法是单次前向或固定集成。CV-BoN 用**关系结果预测 + 约束满足 + 进度项**给 K 个候选打分，只在不确定相位开启。它不是“多模型”，仍是同一个 checkpoint 的多候选采样。
- **技术可行性**：中。①候选生成：策略温度采样 K 个 chunk，或对均值动作做 K 个扰动（更便宜）；②结果预测：轻量关系动力学头预测 `Ĝ_{t+T}`（不要求像素级世界模型，只要求关系级）；③打分：`V = 约束满足 + λ·进度 − 风险`；④延迟：K 次策略前向可批处理；只在相位边界（每 episode 约 5–10 次）开启，摊薄后可控。
- **所需资源**：算力 = 推理 GPU（K=2–4）；数据 = 官方数据训练验证器 + CODA 硬负例；接口 = 无新增字段。
- **落地步骤**：①训练关系结果预测器（输入当前 G + 候选动作块，输出下一关系状态 / 成功概率）；②离线评估 AUROC 与校准；③在线：默认 K=1；相位不确定或 `s_t > τ_s` 时 K=2–4；④延迟守护（U12/U24），超预算立即回退 K=1；⑤记录每个候选的分数与选择，进审计。
- **风险**：①验证器被“什么都不做”欺骗（缓解：进度项 + 多样性 + 硬负例）；②候选不独立，收益低于 iid 上界（见 L9）；③延迟（缓解：批处理 + 相位边界 + 扰动替代重采样）；④验证器自身在 OOD 上失效（缓解：只在它高置信时用，低置信回退策略）。

### IP-12 · CODA 反事实 OOD 增强（P1）

- **动机**：官方训练数据是分布内的，5 类 OOD 轴没有标签。标准域随机化是像素级的，收益已被摊薄；本轮需要**关系级**的反事实：换一个未见但同可供性的物体、加一个会造成遮挡 / 包容冲突的干扰物、换背景、移动位置、加入人。
- **与现有方案的差异**：不是“更多随机噪声”，而是**按官方 5 轴逐轴生成**，并用 CSG 教师自动打关系标签；同时生成“常识硬负例”（看起来合理但违反关系约束的动作），专门训练 IP-11 的验证器。
- **技术可行性**：中。图像空间用 SAM + inpainting / 生成模型做物体替换与背景替换；位置 / 干扰物用几何合成；人可用视频素材叠加。没有仿真器也能做；有仿真器则更好。
- **所需资源**：数据 = 官方数据 + 合成；算力 = 中等（生成 + 打标）；接口 = 无。
- **落地步骤**：①为 5 轴各写一个生成算子 `T_cf`；②生成 + CSG 教师打标 + 人工抽检；③硬负例挖掘（违反约束但视觉合理）；④训练 CSG / 验证器；⑤在真实 OOD 上验证，不用合成指标自嗨。
- **风险**：①合成到真实的鸿沟（缓解：轴特定、少量真机校准）；②生成器偏置（缓解：多生成器 + 真实数据混合）；③标签噪声（缓解：教师一致性过滤）；④覆盖不到测试偏移（见 L13，明确不承诺）。

### IP-13 · CIR 常识不变表示（P1）

- **动机**：OOD 轴改外观，模型容易学“背景 / 纹理 / 颜色”的捷径。关系表示应当对与关系无关的外观不变，同时对**任务相关属性**敏感。
- **与现有方案的差异**：常见做法是无差别域随机化或全局不变性正则；本轮做**选择性不变性**：由语言指令决定哪些属性相关（颜色分拣任务里颜色就是标签，不能扔），只对与关系无关的 nuisance（背景、光照、相机位置、非目标纹理）施加不变性惩罚。
- **技术可行性**：中。用关系标签做监督对比，再加环境间不变性惩罚（IRM / 因果不变性风格）；只训练小适配器或表示头，不动主干。
- **所需资源**：数据 = 官方 + 增强；算力 = 中等；接口 = 无。
- **落地步骤**：①定义 nuisance 与 task-relevant 属性；②关系监督对比；③跨环境不变性惩罚；④消融：去掉颜色相关任务验证不误伤；⑤OOD 评估。
- **风险**：①不变性误删有用信号（缓解：语言条件相关性 + 分任务验证）；②训练不稳定（缓解：小适配器 + trust region）；③收益被 CSG 覆盖（缓解：作为 P1，先看 CSG 单独效果）。

### IP-14 · HRI-C 人机常识与安全（P2）

- **动机**：5 类 OOD 轴中“人为干扰”是唯一涉及动态主体的；它要求社会常识（占用、意图、让行、恢复），而不是纯物理常识。
- **与现有方案的差异**：多数策略把人也当障碍物；HRI-C 把人的占用 / 意图作为关系图的一等节点，输出让行 / 急停 / 恢复策略。
- **技术可行性**：中。人体检测 + 占用预测 + 简单社会规则；不需要复杂意图建模。
- **所需资源**：小；接口 = 无。
- **落地步骤**：①人节点检测与占用区域；②让行 / 急停规则；③恢复策略；④干扰场景真机 A/B。
- **风险**：①误检导致过度保守（缓解：置信度门控 + 可配置灵敏度）；②安全事件（缓解：硬急停优先）；③优先级低（P2）。

## 3. 符号与定义（U13–U24）

| 符号 | 含义 |
|---|---|
| `G_t` | 常识场景图（关系图） |
| `R` | 物理关系谓词集 |
| `α(o)` | 物体可供性签名 |
| `C_t` | 编译后的约束程序 |
| `I` | OOD 不变关系子集 |
| `V_φ` | 常识验证器 |
| `D` | 官方 5 类 OOD 轴 |
| `s_t` | 偏移分数 |
| `T_cf` | 反事实增强算子 |
| `K` | best-of-N 候选数 |
| `(K,B,τ)` | 推理预算三元组 |

**定义 U13（常识场景图）** `G_t = (V_t, E_t, A_t, U_t)`，其中 `V_t` 为物体 / 部件节点，`E_t ⊆ V_t × R × V_t` 为带类型的关系边，`A_t` 为属性 / 可供性，`U_t: E_t → [0,1]` 为每条边的置信度。

**定义 U14（关系谓词集）** `R = R_S ∪ R_C ∪ R_{A/M} ∪ R_{D/H}`：
`R_S = {support, on, stable, hanging, clearance}`；
`R_C = {in, contains, occludes, open, closed}`；
`R_{A/M} = {articulates, rotates, inserts, mates, latches}`；
`R_{D/H} = {fragile, deformable, non_destruction, human_occupied}`。

**定义 U15（可供性签名）** `α(o) = (graspable, pushable, openable, insertable, fragile, deformable, transparent, …) ∈ [0,1]^d`，由 CSG 的节点属性给出。

**定义 U16（约束程序）** `C_t = κ(G_t, ℓ, z_task) = {c_1, …, c_m}`，每条约束 `c_i = (type_i, S_i, bound_i, h_i, conf_i)`，`S_i` 为动作子空间，`h_i ∈ {soft, hard}`，`conf_i` 为谓词置信度。`κ` 为编译器（规则 + LLM 兜底）。

**定义 U17（OOD 不变关系）** `I = {r ∈ R : sup_{d ∈ D} W_1(P(r | o), P(r | o); d) ≤ ε}`，即在 5 轴偏移下条件分布稳定的关系子集。`W_1` 为一阶 Wasserstein 距离；实践中用分桶 KL / TV 近似。

**定义 U18（常识验证器）** `V_φ(G, a_{1:T}) = σ(f_φ(G, a_{1:T}))`，输出“该候选 chunk 满足约束且推进终态”的概率。训练目标为 chunk 级成功 / 约束满足的联合标签。

**定义 U19（验证器引导的候选选择）** `a* = argmax_{k=1..K} [ V_φ(Ĝ_{t+T}^{(k)}, a^{(k)}) + λ·Δprogress^{(k)} − μ·risk^{(k)} ]`，其中 `Ĝ` 为轻量关系动力学预测，`Δprogress` 为阶段推进，`risk` 为碰撞 / 破坏 / 超时风险。

**定义 U20（官方 OOD 轴）** `D = {position, distractor, background, novel_object, human}`，对应赛事的 5 类泛化场景。

**定义 U21（偏移分数）** `s_t = max_{r ∈ I} |p̂_t(r) − p̄_train(r)| / (σ_r + ε)`；`s_t > τ_s` 触发保守模式（提高约束权重 / 开启 BoN / 回退安全策略）。

**定义 U22（反事实增强算子）** `T_cf = {T_pos, T_dis, T_bg, T_novel, T_human}`，每个算子对应一个官方 OOD 轴；增强样本必须落在对应轴的语义内，不得引入轴外偏移。

**定义 U23（合规单模型约束）** ①对外只有一个 checkpoint、一个 `get_action` 服务；②best-of-N 是同一 checkpoint 的多次采样，不加载第二套权重；③不读取评测侧标签 / 端口外信息；④不调用外部在线模型；⑤所有推理期决策可导出审计。

**定义 U24（推理预算）** `(K, B, τ)`：候选数 `K`、每 episode 的 BoN 调用预算 `B`、单步延迟上限 `τ`。默认 `K=1, B=0`；不确定时 `K∈{2,4}, B≤10`；超预算立即回退。

```python
# ===== UniBot-CAIRN 统一策略服务（单 checkpoint、单 API、可回退）=====
class UniBotCAIRNPolicy:                 # 暴露 metadata / get_action / reset
    def __init__(self, ckpt, tau_s=2.0, K_default=1, K_max=4,
                 bon_budget=10, tau_latency_ms=105):
        self.model = load_single_checkpoint(ckpt)   # 主干 + 第 1 轮专家头
        self.csg = CommonsenseSceneGraph()          # IP-09: U13-U15
        self.cac = ConstraintCompiler()             # IP-10: U16
        self.cv  = CommonsenseVerifier()            # IP-11: U18
        self.dyn = RelationDynamics()               # IP-11: Ĝ_{t+T}
        self.shift = ShiftMonitor()                 # U21
        self.audit = AuditLog()                     # 第 1 轮 IP-08
        self.sessions = {}                          # 每端口独立状态

    def reset(self, port=None):
        self.sessions.setdefault(port, Session()).reset()

    def get_action(self, obs, port=None):
        s = self.sessions[port]
        t0 = time.perf_counter()

        # 1) 关系图：低频 / 相位边界才重算，否则用缓存
        if s.need_csg(obs):
            G = self.csg.extract(obs)               # U13
            s.G, s.relations = G, G
        G = s.G

        # 2) 偏移检测：只在不变关系子集 I 上算
        s_t = self.shift.score(G, s.train_stats)    # U21
        if s_t > self.tau_s:
            s.conservative = True

        # 3) 约束编译：每相位一次
        phase = self.phase(obs)                     # 第 1 轮 U3
        C = self.cac.compile(G, obs["observation.language"], phase)  # U16

        # 4) 候选生成：默认 1 个；不确定 / 偏移时 K 个
        K = self.choose_K(s, s_t)                   # U24
        cands = [self.model.act(obs, C, phase) for _ in range(K)]

        # 5) 常识验证 + 选择（不改权重）
        best, best_score = cands[0], -1e9
        for a in cands:
            Gh = self.dyn.predict(G, a)             # 关系级短时预测
            score = self.cv(Gh, a, C) + 0.5 * progress(Gh, G)
            if score > best_score:
                best, best_score = a, score
        self.audit.log_candidates(port, s_t, K, best_score)

        # 6) 延迟守护：超预算回退 K=1 / 安全延拓
        a = self.audit.latency_guard(best, t0, self.tau_latency_ms)
        return self.pack(a, obs)
```

```python
# ===== IP-09：关系图抽取（VLM 候选 + 几何探针 + 小头蒸馏）=====
class CommonsenseSceneGraph:
    def extract(self, obs):
        # 头部双目估深度；腕部近距；EE 位姿给米制尺度
        depth = stereo_depth(obs["cam_left_high"], obs["cam_right_high"])
        nodes = self.detector(obs, depth)            # 物体 / 部件
        edges = {}
        edges.update(self.geom_support(nodes, depth))       # S: 支撑面 / 重心投影
        edges.update(self.geom_containment(nodes, depth))   # C: 包围盒 / 开口
        edges.update(self.vlm_relations(obs, nodes))        # A/M: 轴 / 公母 / 卡扣
        edges = self.calibrate(edges)                       # 温度校准
        return Graph(nodes, edges)
```

```python
# ===== IP-10：约束编译（规则为主，LLM 兜底，schema 校验）=====
def compile_constraints(G, language, phase):
    C = []
    for r in G.edges:
        if r.type == "inserts":            # 公母配合
            C += [AxisAlign(r.axis, tol=2*deg),
                  StraightApproach(r.axis, clearance=r.gap),
                  ContactSearch(step=2*mm, force_proxy_max=...),
                  Latched(r.target)]
        elif r.type == "articulates":      # 关节 / 旋转
            C += [Helical(r.axis, pitch=r.pitch),
                  TorqueProxyMax(...), RotateToLimit(r.range)]
        elif r.type == "contains":         # 包容
            C += [ApproachFromOpening(r.opening), Corridor(r.obstacles),
                  NonTargetImmutable(r.others)]
        elif r.type == "support":          # 支撑 / 堆叠
            C += [VerticalDescend(r.axis), ReleaseHeight(r.h),
                  CenterOfMassProjection(r.support_poly)]
    C += llm_fallback_constraints(G, language)   # 未见关系
    validate_schema(C)                           # 非法即丢弃
    return mark_soft_hard(C)                     # 默认 soft；不可逆伤害才 hard
```

```python
# ===== IP-11：验证器 + 候选选择（关系级，不要求像素世界模型）=====
class CommonsenseVerifier:
    def __call__(self, G_next, a_chunk, C):
        constraint_ok = sum(c.satisfied(G_next) * c.weight for c in C)
        risk = self.risk_head(G_next, a_chunk)   # 碰撞 / 破坏 / 超时
        return sigmoid(self.score_head(G_next, constraint_ok, risk))
```

## 5. 推导（引理 L8–L14）

**引理 L8（不变量迁移界）** 设关系编码器 `Φ: O → G`，策略 `π(a|o) = π̄(a | Φ(o), φ_obj(o))`。若对任意 `d ∈ D` 有 `P(Φ(o) | d) = P(Φ(o))`（关系分布不变），且 `Φ` 的估计误差为 `ε`，则 `|R_d(π) − R_train(π)| ≤ L_π·ε + O(estimation)`。直观：外观偏移不能直接伤害策略，残余差距只来自关系估计误差。**前提是关系确实充分**；若任务还依赖关系之外的属性（如颜色分拣），必须把这些属性并入条件。∎

**引理 L9（验证器引导的收益条件）** 设单候选成功率为 `p`，候选独立，验证器为完美选择器，则 `P(success_BoN) = 1 − (1−p)^K`。若验证器排序 AUC 为 `A`，可近似定义有效候选数 `K_eff ≈ 1 + (K−1)(2A−1)`；故收益要求 `A > 0.5` 且候选有多样性。若验证器与策略错误相关，则 `K_eff` 进一步下降。实践中 `A ≥ 0.75, K=4` 才有稳定 +2 分。∎

**引理 L10（软约束的安全性）** 若硬约束仅在 `conf_i > τ` 时激活，且在该置信度下谓词正确的概率 `≥ 1−ε`，则基线成功动作被错误排除的概率 `≤ ε·m`（`m` 条约束的并集界）。取 `τ` 使 `ε·m·L_max ≤ 0.5` 分，即可保证“不因常识误判而显著伤害基线”。软约束的损失则由惩罚权重连续控制。∎

**引理 L11（常识误判的不对称性）** 设假阳性（幻觉出一个关系）成本 `C_FP`，假阴性（漏掉一个关系）成本 `C_FN`。贝叶斯最优阈值 `τ* = C_FN / (C_FN + C_FP)`。由于幻觉关系可能导致破坏性动作（`C_FP ≫ C_FN`），最优策略偏向**高精度、低召回**：不确定时选择“不干预 / 回退”，而不是激进执行。∎

**引理 L12（声明式—程序式鸿沟）** 设谓词准确率 `p_r`，在谓词正确时约束可执行且正确的概率 `p_{e|r}`，关系链长度 `m`，则端到端成功率上界 `≤ (p_r · p_{e|r})^m`。取 `p_r=0.9, p_{e|r}=0.8, m=3`，上界仅 `0.37`。这解释了“VLM 答对 ≠ 机器人做到”，也是本轮必须做 **compile-and-execute 基准**（E621）的原因；工程上应减少每阶段的关系链长度，只编译当前最关键的一条。∎

**引理 L13（反事实覆盖界）** 反事实增强只在测试偏移 `d` 落在生成算子 `T_cf` 的支撑集内时提供保证：`d ∈ supp(T_cf) ⇒` 期望风险可由增强分布上的经验风险界定；否则无保证。因此 CODA 必须**按官方 5 轴逐轴生成**，并明确不承诺轴外偏移。∎

**引理 L14（推理预算的边际收益）** 给定单候选成本 `c_p`、验证器成本 `c_v`、延迟预算 `τ`，最优 `K* = argmax_{K} S(K) s.t. K·c_p + c_v ≤ τ`，其中 `S(K)` 由 L9 给出。`S(K)` 边际递减；当 `c_p` 大时，用“均值动作扰动”替代“完整重采样”，可在几乎不增成本的情况下获得候选多样性。∎

- **必保**：IP-09（关系图）、IP-11（验证器）。前者是信息价值，后者是机制正确性。
