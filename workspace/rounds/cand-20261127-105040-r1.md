## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（需求洞察 → 先看清"分数从哪里来"，再决定练什么）**
直觉：前两轮一直在问"怎么让策略更强"，却没问"分数函数到底奖励什么"。本轮把 32 份 info.json 全抓下来，答案很直白：(a) 分数是**有序里程碑**，不是成功/失败二值——2~5 个步骤、每步 20~50 分，走到第 2 步就有分；(b) 官方 `human_4` 大量是**中途撤销**（把锁拿走、把拉链拉开、把叠好的毛巾翻开、把叠上的碗拿下来）——评测在考"进度被打断/回退后能否恢复"，而训练集全是干净成功；(c) 泛化覆盖不均衡，23/32 考未见物体、2 个任务压根没有泛化字段。核心反直觉点：**最高性价比不是把易任务从 90 做到 95，而是在难任务/被撤销场景把 0 做到 1——步骤分是稠密的部分信用，恢复能力是官方明写的考点。**

**灵感 2（专利布局 → 别"申请"9 个点子，要组一个能守住的组合）**
直觉：把 I1–I9 当 9 份专利来审，会立刻发现大部分是"在先技术"：LoRA、ConcatDataset、Diffusion Policy、世界模型、低延迟 serving 都是官方 baseline 或公开论文已有的，属于**现有技术（prior art）**，写得再漂亮也不构成差异。真正能"占住"的只有一条主线：**用官方评分卡（F20–F24）驱动数据与目标函数**——它依赖这份特定赛事的原始字段，别人没挖到就无法快速复制。于是组合应收敛为：1 个**核心**（评分卡编译器）→ 2 个**核心从属**（考纲校准增广、恢复示教+里程碑目标）→ 2 个**外围**（检索、加权共训）→ 1 个**表内必备但无差异**（serving）→ 1 个**弃案**（世界模型 TTA）。核心反直觉点：**在公开基座上，护城河不是模型结构，而是"把公开考纲变成私有数据引擎"的执行速度与组合深度；专利布局在这里的真实含义是"预算组合配置"，不是法律申请。**

**两者统一（需求侧 × 可防御性）**：需求洞察回答"哪些分最容易拿"（里程碑部分分 + 撤销恢复 + 未见物体），专利布局回答"哪些投入最守得住"（依赖评分卡原始字段的那条链）。二者交集即本轮结论：**把 80% 的数据/训练预算押在"评分卡编译器 → 考纲校准增广 + 恢复示教 + 里程碑目标"这条主链上；世界模型、混合伺服等高 FTO/高延迟风险项降为弃案或防御预案。**

## 2. 对第 2 轮痛点的增量修订

- P1（弱任务洼地）细化：难度与步骤粒度已知，可按"边际步骤分密度"而非"任务数"分配预算。
- P2（泛化缺口）升级：从"按考纲卡校准"升级为"直接解析官方 `generalization` 原始字段"，偏差源从"wiki 转述"变为"官方 JSON 是否完整"。
- P5（时间压力）升级：步骤分有序且可自动判定 → 里程碑检测器从"自造"改为"官方 `score_steps` 直译"。
- P7（先手窗口）强化：官方评分卡已可机器读取，先挖到并编译成训练目标的一方获得结构性先手。
- 新增 **P9（公开考纲过拟合）**：公开字段可能不等于真实评测全集（T31/T32 无泛化字段、排序权重未公布），存在"按考纲刷题"的过拟合风险。

## 3. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

- **Q9（评分卡可编译性）**：32 份 info.json 能否编译成统一的"有序里程碑图 + 扰动轴集合"，并自动生成里程碑验证器与步骤分代理？哪些字段需 LLM 补全、误差如何界定？
- **Q10（恢复的边际价值）**：官方 `human_4` 型"撤销/移开"扰动对步骤分的期望损失有多大？合成恢复示教（I5 v3）能挽回多少，是否存在"恢复动作分布外"风险？
- **Q11（组合预算）**：在固定算力/真机预算下，按"边际步骤分密度 × 可防御性"分配 32 任务的训练与消融预算，与均分/按难度分配相比，期望总分提升多少？

## 4. 设计原则（新增 PR6/PR7，其余保留）

- **PR6 评分卡优先律（需求侧）**：任何训练信号/增广/恢复合成，先问"它对准哪个官方 `score_step` 或 `generalization` 轴"；对不上任何字段的默认低优先。与 PR5 数据杠杆律互补：PR5 管数据来源，PR6 管分数来源。
- **PR7 组合防御律（专利侧）**：每个创新点必须标注 `核心/外围/防御/弃案` 与"新颖性来源"；核心链只允许依赖"公开但需挖掘"的赛事专属资产，不允许核心依赖高 FTO 风险（单模型边界/延迟）的模块。
- PR1–PR5 保留（第 2 轮 §4）。

> **组合律（PR7）**：核心链（I10→I1/I5）不允许依赖 I3/I7；这样即使 I3 因"单模型"裁定被禁、I7 因延迟被砍，主链仍完整可提交。I7 的预算与 WMA-0 资产并入 I5 数据引擎。

## 2. 新增/升级创新点定义（动机 / 差异 / 可行性 / 资源 / 步骤 / 风险）

### I10 评分卡编译器 ★★★★★（核心，新增）
- **动机**：官方已把每任务"有序里程碑 + 分值 + 泛化轴"以 JSON 公开（F20–F24），但它是散落的 32 份文件；把它编译成统一结构，才能同时喂给增广（I1）、恢复（I5）、消融（I8）与预算（I11）。
- **与现有方案差异**：别人把 `scoring_points` 当"说明文字"读；本点把它当"可执行规格（executable spec）"编译成图与验证器。
- **技术可行性**：高。纯解析 + LLM 抽取目标物体/关系；`score_steps` 已是结构化数组，`generalization` 已是键值对，主要是归一化与验证器补全。
- **所需资源**：1 人周工程；无需 GPU。
- **落地步骤**：①抓取 32×info.json 并版本锁定；②统一 `Rubric` 数据类（里程碑/分值/轴/目标物体）；③为每步生成视觉/几何验证器草案（开放词汇检测 + 状态机）；④覆盖率与误差审计（人工抽检）；⑤导出给 I1/I5/I8/I11 的接口。
- **风险**：文本到验证器的语义鸿沟（如"摆正""对齐"难自动判定）；缓解：验证器只作训练标注/代理指标，不作最终裁判；对模糊步骤用人工 5% 抽检校准。

### I11 组合预算调度器 ★★★★（元层，新增）
- **动机**：32 任务难度与步骤粒度不同，均分预算必然浪费；"专利布局"的真实可操作版本就是"预算组合配置"。
- **与现有方案差异**：常见做法按任务数或按难度均分；本点按**边际步骤分密度**（可拿步骤分 / 训练成本）× 可防御性排序分配。
- **技术可行性**：高（离线仿真 + 简单优化）。
- **所需资源**：1 人周；复用 I8 的 L0 代理。
- **落地步骤**：①用基线在留出集估每任务"首里程碑/全里程碑"可达概率；②算 ρ_t；③核心任务保底 + 其余按 ρ_t 分配；④每轮用真机结果回填更新 ρ_t。
- **风险**：ρ_t 估计偏差导致"过早放弃难任务"；缓解：设 5% 预算下限给所有任务，难任务只在连续两轮 L0 无改善后才降权。

### I1 v3 考纲校准增广引擎（核心从属，升级）
- 第 2 轮的"考纲卡"从"LLM 解析 wiki"升级为**直接由 `generalization` 原始字段生成**：`human_1`（位置偏移方向/对象）、`human_4`（对抗/撤销动作）、`unseen_object_3`（未见物体类别）逐任务实例化为增广参数与"模拟考题"。
- 新增判据：增广后的样本必须能映射到某个具体 `score_step`，否则丢弃（PR6）。
- 保留风险与降级预案：位置重拼接的"不可行动作占比 >5% 即降级为平移不变增广"。

### I5 v3 恢复示教 + 里程碑目标（核心从属，升级）
- 第 2 轮的"扰动重放/跨段缝合"聚焦到**官方撤销型扰动**：对 0.1 的 14 个任务，按 `human_4` 语义（拿走/移开/拔起/拉开/翻开/拿下/放回起点）构造"进度回退→重新达成"的合成示教；质量门禁 = 是否重新达成下一个官方 `score_step`。
- 进度头目标从"自造里程碑"改为**官方 `score_steps` 序数**：标签自动、可复现，且直接对齐排行榜的步骤分。
- 保留风险：合成分布与真实偏离失配；缓解：扰动幅度/方向从 `generalization` 文本与示例视频反推，L0 先验证不伤标称。

### I8 v3 评测闭环（外围/度量，升级）
- L0 代理从"泛 Δprog"改为**直接预测步骤分**：`Δstep = E[step score | 扰动] - E[step score | 标称]`，并按任务/轴分层。
- 注册表继续记录"离线 Δstep vs 真机 Δstep"的 Spearman；某代理相关性 >0.6 才可单独准入 L2。

### I7 弃案 / I3 防御（修剪）
- **I7**：官方 WMA-0 已公开且主打仿真数据生成，测试时 rollout 延迟与"单模型"合规双重风险，无差异化价值 → 停止投入，资产转 I5 合成数据。
- **I3**：混合关键点伺服仍可能触碰"单模型"边界（PR7 FTO=中）→ 只保留"训练时辅助监督"的 I3' 预案，不占主链预算。

## 3. 关键伪代码

### 3.1 I10 评分卡编译器

```python
from dataclasses import dataclass

@dataclass
class Milestone:
    idx: int
    zh: str
    pts: int
    target: str        # LLM 从文本抽出的目标物体/关系
    verify: object     # 视觉/几何验证器草案（训练标注用，非最终裁判）

@dataclass
class Rubric:
    tid: str; slug: str; en: str; difficulty: str
    milestones: list          # 有序，sum(pts) == 100
    axes: dict                # {"human_1": "...", "human_4": "...", "unseen_object_3": "..."}
    recovery: bool            # h1/h4 是否含撤销/移开/拔起/拉开/翻开/拿走

REGRESS_PAT = ("拿走", "移开", "拔起", "拉开", "翻开", "拿下", "放回", "拧回", "打开")

def compile_rubric(info: dict) -> Rubric:
    steps = info.get("score_steps") or parse_cn_steps(info["scoring_points"])
    assert sum(s["score"] for s in steps) == 100
    axes = info.get("generalization", {})
    return Rubric(
        tid=info["task_id"], slug=info["slug"], en=info["en_name"],
        difficulty=info["difficulty_en"],
        milestones=[Milestone(i, s["zh"], s["score"], extract_target(s), None)
                    for i, s in enumerate(steps)],
        axes=axes,
        recovery=any(any(p in v for p in REGRESS_PAT) for v in axes.values()),
    )
```

### 3.2 I5 v3：把 `human_4` 撤销语义变成合成恢复示教

```python
def synthesize_recovery(eps, rubric, axis="human_4"):
    """在已达成里程碑 t 后注入官方撤销算子，生成‘回退→重新达成’段。"""
    op = regress_operator(rubric.axes[axis])          # 拿走/移开/拔起/拉开/翻开...
    for (t, state, action) in eps:
        if milestone_reached(rubric, t) and rubric.recovery:
            pert = inject(state, op)                   # 施加官方语义扰动
            seg  = replay_policy_or_expert(pert)       # 续写恢复段
            if milestone_reached(rubric, seg.end) >= milestone_reached(rubric, t):
                yield pert, seg                       # 只有恢复成功才保留
```

### 3.3 I5/I8：里程碑序数目标与步骤分代理

```python
def rubric_progress_loss(pred, rubric, traj):
    # 标签 = 官方里程碑序数 / 总数，自动生成、单调
    y = milestone_ordinal(traj, rubric) / len(rubric.milestones)
    return smooth_l1(pred, y) + monotonic_penalty(pred)

def rubric_L0(policy, heldout, rubric):
    # 代理指标直接对齐排行榜的步骤分，而不是泛泛的动作一致性
    nominal = expected_step_score(policy, heldout)
    pert    = expected_step_score(policy, perturb_by_axes(heldout, rubric.axes))
    return {"d_step": pert - nominal, "by_axis": per_axis(pert)}
```

### 3.4 I11 组合预算分配

```python
def marginal_score_density(rubric, base_step_score, cost):
    return base_step_score[rubric.slug] / (cost[rubric.slug] + 1e-6)

def allocate(rubrics, budget, floor=0.05):
    rho = {r.slug: marginal_score_density(r, BASE, COST) for r in rubrics}
    alloc = {s: floor * budget / len(rubrics) for s in rho}      # 5% 保底
    rest  = budget - sum(alloc.values())
    total = sum(rho.values())
    for s in rho:
        alloc[s] += rest * rho[s] / total                        # 边际分密度加权
    return alloc
```
