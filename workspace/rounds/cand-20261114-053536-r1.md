# 第 72 轮（承接第 71 轮「GAUGE-RAS 计量审计层」IP-275~286；灵感循环第 1 轮；本轮灵感：「角色一致性」×「灵巧操作」）

> R71 审计了「尺子」——它把 H[b_t]、ECE、VoI、延迟、成功率升级为带构造效度、不确定度预算、有效性域、反 Goodhart 对偶与追溯链的测量结果，并让安全成为不可补偿的否决项。但 R71 仍然默认了一个比「尺子可信」更深、且从未被写进证书的前提：**我们知道自己量的是「谁在扮演什么角色」。** 它假设接触点是固定的、信息源是已知的、机器人是助手、人是委托人、手指的接触功能在测量期间不变。可这些「角色」不是被观测到的，而是**被指派的潜在变量**。同一个触觉/力序列，在「拇指是支点、食指在滑移」与「拇指在滑移、食指是支点」两种角色指派下，含义完全不同；同一句「我先做这一步」，在「助手」与「主导者」两种角色下，规范性含义完全相反。R71 可以证明每条读数在其有效性域内可信，却无法证明**读数被正确地贴上了角色标签**。
>
> 灵巧操作把这个漏洞变成不可回避的硬约束。多指、接触富集、in-hand 操作的本质就是**接触角色的持续再指派**（pivot / slider / stabilizer / explorer / load-bearing），而力封闭只在给定接触角色下才有定义。角色一旦被悄悄换掉（滑移、再抓取、手指接管、从捏到握），每个力/触觉读数仍然「校准良好」，但整只手的安全判据已经失效。**力封闭不是手–物系统的属性，而是手–物系统在某个角色指派下的属性。** 更糟的是：当两指功能对称时，角色指派会出现标签互换（label switching），后验熵很大却完全无害；当两指功能不对称而观测不足时，后验可能很尖却「自信地贴在错误角色上」——这两种情况 R71 的 H[b_t] 都无法区分。
>
> 角色一致性补上另一半，而它与灵巧操作共享同一个形式核心。它既是「同一角色跨时间由同一承担者保持」（接触角色 / 实体身份的一致），也是「声明的角色与执行的角色一致」（persona / commitment 的一致）。前者是**指派的稳定性**，后者是**承诺的兑现**。两者都可以写成：角色是一个带义务 / 权限 / 不变式的类型化对象，一致性是「同一角色契约在时间、模态与执行者之间没有被偷偷改写」。而在人机共处中，机器人的执行角色又会反过来改变人的角色与信任（人越让步，机器人越主导，声明越失真）——这是 R71 反作用动力学在**角色维度**上的推广。
>
> 核心命题：**不要只问「这把尺子可信吗」，还要问「我们是否把读数贴到了正确的角色上；这个角色指派是否可辨识、是否稳定、是否与我们声明的承诺一致」。** 把 R71 的测量层再往下压一层：在其有效性域的元条件里，显式写入「角色指派 + 角色契约」。命名 **ROLE-RAS**（Role-consistent, Ontology-grounded, Latent-assignment Evidence for RAS；角色一致 × 接触本体 × 潜在指派 × 证据闭环）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「我该信哪个状态」，R71 问「量它的那把尺子可信吗」，R72 问「**在量之前，谁在扮演什么角色；量完之后，这个角色有没有被悄悄换掉、被事后重贴标签、或被我们自己演成了另一个角色**」——角色一致性不是要最大化的分数，而是一条**可辨识、可切换、可兑现、且不可追溯篡改**的角色契约。

## 0. 直觉与动机

**灵感 1（角色一致性 → 角色是潜在指派，不是已知标签）**
直觉：我们看一段多指操作，会很自然地描述「拇指在当支点，食指在滑」。但这个描述不是传感器直接给出的：它是我们**从接触、力、运动里推断出来的一份角色指派**。传感器给的是「接触点 3 的法向力上升、切向速度非零」，不是「拇指是支点」。把观测翻译成角色，是一个**数据关联（data association）**问题。多目标跟踪里最经典的失败不是「位置估错」，而是「把 A 的观测配给了 B」（标签互换）；在灵巧操作里，最经典的失败也不是「力估错」，而是**把不同接触的功能角色配反了**——于是力封闭判据作用在了错误的约束集上。

**灵感 2（灵巧操作 → 力封闭是角色条件的，滑移是角色切换的证据）**
直觉：抓稳一个杯子，靠的不是「力够大」，而是「哪些接触点承担了哪些约束」。同样的接触力分布，在「三点捏」与「掌心托 + 两指夹」两种角色下，稳定域完全不同。滑移（incipient slip）、滚动、手指 gaiting、再抓取，本质上都是**接触角色发生转移**。所以「检测到滑移」不只是噪声变大，而是**角色指派需要变更**的信号。若系统把滑移误判成扰动、继续用旧的力分配，它会在角色已经换了之后，仍按旧角色证明自己「力封闭」——这是灵巧手最隐蔽的不安全。

**灵感 3（声明 vs 执行 → persona 一致性是带时态的义务，不是语气相似）**
直觉：一个机器人说「我是助手，不会擅自结束任务」，然后它擅自结束了；或者说「我只在你确认后移动」，然后它先动了。单看每一帧，动作都合理；单看每句话，措辞都得体；**但声明角色与执行角色不一致**。角色一致性不是「说话风格一致」，而是**承诺的时态逻辑在整条轨迹上被满足**：在角色释放之前，某类动作永远不发生。它和 R71 的情感通道相接：语义、韵律、动作是同一份承诺的三个证据通道，任何一个通道都在说「我是助手」，而动作在说「我是主导者」，就是跨模态角色冲突。

**灵感 4（一致性 ≠ 充分性 → 永不换角色是「完美一致地错误」）**
直觉：如果只把「角色一致性」当目标，最优解是**永远不换角色**：声明什么就永远演什么，一致性满分，任务却可能彻底失败。这在分层/灵巧系统里尤其致命——抓取必须从「接近」切到「闭合」再到「抬起」，不换角色就永远抬不起来。所以一致性必须是一个**约束**（不得在未认证时偷偷换、不得违反声明义务），而不是一个**要最大化的分数**；它必须配一个「角色充分性 / 任务适配」的反指标，否则优化器会用「一致地不动」换取分数。这是 R71 Goodhart 教训在角色维度的重演，且更隐蔽：指标本身看起来是在保护安全。

**灵感 5（切换与交接 → 接缝处的「双主 / 无主」比单点错误更危险）**
直觉：灵巧操作里最危险的瞬间是**角色交接的瞬间**：从拇指支点到食指支点、从一手到另一手、从机器人到人。若「先释放再获取」，中间会出现**无主窗口**（没人负责稳定，物体掉落）；若「先获取再释放」，会出现**双主窗口**（两只手指同时以为自己是支点，力冲突、内应力、甚至掰断物体）。这正好是分布式系统里的原子提交问题：不可能同时保证「分区下既安全又活」。角色交接必须显式协议化，并且在通信不可靠时**默认安全侧（保持原主并冻结）**，而不是「谁先到谁当主」。

**灵感 6（反作用 → 机器人的角色会把人变成另一个角色）**
直觉：机器人一直用「主导者」的语气和节奏，人会慢慢从「共同决策者」退化成「被动执行者」；机器人一直用「助手」姿态，人可能把危险决策的責任也推给它。角色的执行会**改变对方对角色的承担**，进而改变对方提供证据的方式（R71 的 ψ 与 c(ψ)）。于是「角色漂移」不是内部记账问题，而是一个会自我强化的闭环：声明是助手 → 实际越来越主导 → 人越来越依赖 → 声明越来越假 → 人仍然按「助手」预期放行。R71 的信任预算需要再加一个**角色预算**。

**灵感 7（严格包含 → 单角色、静态接触是退化情形）**
直觉：如果只有一个实体、一个平凡角色、接触角色恒定、声明与执行无区别、角色可辨识度为 0 误差，那么 ROLE 必须**逐指令退化为 GAUGE-RAS**，再退化为 BELIEF/FLUID/R68。角色层不能靠「多信一个本体模型」换取能力，而必须靠「角色可辨识且契约可证时启用，否则退回角色无关的保守策略」。**新层只允许在它自己的有效性域内存在。**

## 1. 形式化定义（增量：定义 349–366）

**定义 349（ROLE-RAS 总览）** ROLE-RAS = (ROL, RAE, RID, RSC, RCC, DCR, RFA, HOR, RRB, RGA, AIC-ROLE, J_ROLE, GAUGE-RAS†)。四不变式：
(i) **零学习写操作**（继承 R70 定义 310-i、R71 定义 331-i）；角色变更与交接是带审计与证书的**安全状态转移**，不是梯度更新；
(ii) **角色完整性**：凡参与高风险决策的角色，必须携带 (本体版本, 指派后验, 可辨识性缺口, 切换证书, 角色追溯链 τ_role)；缺一即不得进入否决；
(iii) **歧义鲁棒的非补偿安全**：角色条件下的安全否决对**可信指派集合**取最坏情形（∀α ∈ 𝔄^c），性能不得补偿任一可信指派下的越界；
(iv) **一致–充分分离**：角色一致性是约束 / 承诺，不是标量目标；任何一致性指标必须与角色充分性反指标成对出现，否则不得在线优化。

**定义 350（角色本体 ROL）** 角色本体 R = (ℛ, ≼, Obl, Perm, Inv, ver)：ℛ 为类型化角色集，≼ 为角色特化偏序（子角色可继承并加严），Obl/Perm 为义务与权限，Inv 为不变式，ver 为版本。至少三类角色：
- **任务角色**：主导者 / 助手 / 观察者 / 安全监督者；
- **接触角色**：支点 pivot / 滑动 slider / 稳定 stabilizer / 探索 explorer / 释放 release / 承载 load-bearing；
- **社会角色**：委托人 principal / 代理 agent / 同伴 peer。
角色可组合（复合角色），但组合必须通过本体类型检查。**本体是「角色能做什么、必须做什么、禁止做什么」的可证伪契约，而不是一张标签表。**

**定义 351（角色指派 α_t）** 设实体集 E_t（手指、接触点、手、人、机器人）。角色指派 α_t: E_t ⇀ ℛ 为**部分单射**，且满足本体约束 α_t(e) ≼ 该实体的能力类型。𝔄_t 为所有可容许指派；G 为在观测下保持等价的标签置换群。α_t 不是世界状态 s_t 的一部分，而是对 s_t 的**关系性解释**；历史 A_{0:t} = (α_0, …, α_t) 带时间戳与证据。**同一个 s_t 在不同 α_t 下有不同的安全含义。**

**定义 352（角色条件模型）** 联合后验 q_t(s_t, α_t) ∝ p(o_{1:t} | s_t, α_t) · p(s_t | α_t) · p(α_t | A_{0:t−1})。角色条件动力学/观测为 p(s_{t+1}|s_t,a_t,α_t)、p(o_t|s_t,α_t)：接触角色决定哪个接触点被约束、哪条边承载、哪根手指可动。**角色不是噪声参数，它改变模型结构本身。**

**定义 353（角色可辨识性缺口 RID）** 设 ≡_obs 为观测等价（两指派对所有任务相关观测给出同一分布），≡_safe 为安全等价（两指派在同一角色条件安全判据下给出同一通过/否决）。定义：
- **观测可辨识缺口** RID_obs = H[q / ≡_obs]（按观测等价类商掉后的熵）；
- **安全可辨识缺口** RID_safe = 1 − q_t([α*_t]_{≡_safe})，即「与 MAP 安全判决不同的指派」的后验质量。
关键性质：标签对称时 H[α] 很大而 RID_obs/RID_safe 很小（良性歧义）；后验很尖但贴在安全不等价类上时 H[α] 很小而 RID_safe 很大（**自信地错角色**）。R71 的 H[b_t] 对这两者都无感。

**定义 354（角色一致后验 RCP）** 在定义 352 上施加**一致性投影**：删除与已声明义务或已认证切换不一致的指派（除非完成重声明），
q^R_t(s,α) ∝ q_t(s,α) · 1[α ∈ 𝔄_consistent(t)] · 1[α 的历史与 A_{0:t} 的切换证书相容]。
边缘 b^α_t(s) = q^R_t(s|α)。高风险决策不使用简单的后验均值，而进入定义 358 的集合级否决。

**定义 355（角色切换证书 RSC）** 角色切换事件 τ 把角色 r 从实体 e 转移到 e'（或改变功能角色）。证书 T_switch = (τ, r, e→e', ΔLLR, δ_false, δ_missed, dwell_min, two_phase_id, τ_chain)。接受切换需同时满足：
(a) 证据对数似然比 ΔLLR 超过阈值（切换确有证据）；
(b) **驻留 / 迟滞** dwell ≥ dwell_min（防抖动、防「一滑就换」）；
(c) 完成 HOR 两阶段交接（定义 359）；
(d) 切换窗口内无未解决的角色安全否决。
**无证书的切换即角色违规（role violation），一律降级。** δ_false/δ_missed 是切换检测的假切换/漏切换界。

**定义 356（角色承诺一致性 RCC）** 声明角色携带时态逻辑承诺 K（例如 `G(¬move_without_consent) U role_released`、`G(assistant ⇒ ¬unilaterally_end_task)`、`G(reports_uncertainty)`）。执行轨迹 ξ 的一致性判定为 ρ_K(ξ) ∈ {0,1} 及违反见证 witness；角色漂移 drift = d(α^decl, α^act)（声明角色与执行角色的距离，按本体 ≼ 与义务差定义）。**一致性不仅是「声明与动作不矛盾」，还包括「声明与自模型能力不矛盾」（不能声称自己能做 β 已禁止的事）与「声明与权限不矛盾」。**

**定义 357（灵巧接触角色图 DCR）** 接触角色图 G_c = (V_c, E_c, ρ_c)：V_c 为接触点/连杆，E_c 为接触/约束边，ρ_c: E_c → 接触角色。定义**角色条件力封闭** FC(G_c, α, μ, f_ext) 为：在指派 α 决定的约束集上，存在满足摩擦锥与外力平衡的内力分布。滑移模型 p(slip_t | α, tactile_t) 依赖角色；incipient slip 是 pivot→slider 的证据，不是普通噪声。**再抓取 = 角色切换；手指 gaiting = 角色交接。** 力封闭必须在**每个可信 α** 下复核（定义 358）。

**定义 358（歧义鲁棒角色安全 RFA）** 取可信指派集 𝔄^c_t = 后验质量 ≥ 1−δ 的最小集合。高风险动作 a 的角色安全否决为
V_role(t,a) = 1[ ∃α ∈ 𝔄^c_t : ¬Safe(α, b^α_t, a) ∨ ¬FC(G_c, α, μ, f) ]。
即**只要任一可信角色指派下不安全，就否决**（Hannan / 鲁棒贝叶斯式，而非后验均值）。低风险动作可用带歧义惩罚的期望风险，但歧义惩罚不得为负、不得补偿硬项。RID→0 时退化为 MAP 安全。

**定义 359（角色交接协议 HOR）** 角色 r 的交接是三阶段：**prepare**（e' 进入 ready/影子状态、能力与力分配就绪）→ **commit**（以单调 epoch 令牌原子切换所有权）→ **retire**（e 退出并释放）。不变式：安全关键角色**至多一个 owner**（唯一所有权）且**不存在无主窗口**（始终有 owner）。通信分区时默认 **fail-safe hold**：保持最后 owner 并冻结角色相关动作，牺牲活性、保留安全性。**「先释放后获取」允许无主窗口，「先获取后释放」允许双主窗口；只有令牌化两阶段提交能同时排除二者（在可靠全序提交下）。**

**定义 360（角色反作用动力学 RRB）** 机器人执行角色影响人的角色与 ψ：
ψ_{t+1} = T(ψ_t, g_t, ρ_robot, α^robot_t)，α^human_{t+1} = T_role(α^human_t, α^robot_t, ψ_t)。
定义角色预算：累计切换次数、切换率与漂移幅度 Σ_t [c_switch + λ_d·drift_t] ≤ B_role。当 drift > τ_redeclare 时**必须主动重声明 / 重新协商角色**，不能沿用旧声明。**机器人不能单方面「演成」另一个角色而不更新契约。**

**定义 361（角色 Goodhart 对偶 RGA）** 每个角色指标 m 配一个同构念、异偏差的反指标 m⊥：
- 一致性 ↔ **角色充分性 / 任务适配**（永不切换：一致性满分、充分性归零）；
- 声明–执行保真度 ↔ **独立承诺审计**（自报 vs 冻结日志）；
- 切换精确率 ↔ **适配延迟**（不切换：无假切换、但角色陈旧）；
- 角色稳定性 ↔ **角色响应性**。
间隙 D_role = |m − m⊥| 超阈值 ⇒ 该角色指标在本次决策中失效（继承 R71 GAP/IVG）。**「一致」永远不能单独作为放行理由。**

**定义 362（角色证据纪律）** 接受一个安全关键角色需同时具备：实体身份证据（本体/触觉/视觉）、功能角色证据（接触力/运动/约束）、声明证据（语言/契约），且至少一个正交通道不矛盾。**任何单一模态不得单独定案角色**；跨模态「过度一致」也要警惕（伪造触觉 + 伪造视觉的共谋欺骗）。一致性是必要的，不是充分的。延伸 R71 定义 343。

**定义 363（角色追溯链 TCHAIN-role）** 每个进入 J_ROLE 的角色附带 τ_role = (ontology_ver, assignment_history_hash, switch_cert_ids, declared_commitments_hash, evidence_sources, timestamp, validity_interval)。任一环缺失 / 过期 ⇒ 该角色降级为「未验证角色」，不得进入 RFA 的通过依据。**没有角色溯源，就没有角色否决。**

**定义 364（威胁模型 AIC-ROLE）** ℰ_ROLE = ℰ_GAUGE × ℰ_role：
ℰ_role = {实体身份伪装、接触角色误配（对抗物体/手指）、**事后重贴标签**（retroactive relabeling 以维持「一直一致」）、切换 gaming（在交接点把 false-done 当完成）、本体投毒（错误角色类型/义务）、persona 漂移与谄媚（为取悦人而改变声明角色）、交接双主/无主攻击、跨模态角色共谋}。

**定义 365（证书 J_ROLE）** J_ROLE = (J_GAUGE, ontology_ver, role_posterior_summary, RID_obs, RID_safe, switch_certs, declared_commitments, commitment_audit, role_budget_state, FC_check_set, handover_state, role_trace)。
Valid ⇔ Valid(J_GAUGE) ∧ RID_safe ≤ τ_safe ∧ RID_obs ≤ τ_obs ∧ 承诺未被违反 ∧ 切换证书有效 ∧ ∀α∈𝔄^c FC 通过 ∧ 交接不变式成立 ∧ 角色预算未超。

**定义 366（流水线与严格包含）** 高频伺服（R71 原样）／中频接触与角色检查（10–20Hz，触觉 + 本体）／低频角色重估与重声明（1–5Hz）＋事件触发的 RSC/HOR/RCC。**角色审计绝不进入伺服快路径；交接只在事件 tick 原子提交。** 当单实体、单平凡角色、接触静态、指派确定（RID=0）、声明与执行无区别、无角色预算时，ROLE-RAS 逐指令等于 GAUGE-RAS，再按 R71 定义 348 退化 BELIEF/FLUID/R68。

## 2. 关键算法骨架

```python
# IP-287 ROL：角色本体（类型化、版本化、可审计；不在线学习修改）
class RoleOntology:
    def __init__(self, roles, leq, obligations, permissions, invariants, ver):
        self.R, self.leq, self.Obl, self.Perm, self.Inv, self.ver = \
            roles, leq, obligations, permissions, invariants, ver
    def admissible(self, task):                     # 返回任务允许的角色类型
        return [r for r in self.R if task.requires(r)]
    def typecheck(self, composite):                 # 复合角色必须通过本体检查
        return all(self.Inv[r](composite) for r in composite)

# IP-288 RAE：角色指派后验（实体身份由本体/触觉/视觉锚定；保留标签对称群）
class RoleAssigner:
    def update(self, obs, tactile, proprio, history):
        # 因子图 / 粒子：节点=接触/实体，边=角色约束与运动一致性
        self.q = self.filter.step(obs, tactile, proprio, history)   # q(alpha)
        return self.q
    def credible_set(self, q, mass=0.99):
        return min_mass_set(q, mass)                 # 可信指派集 A^c

# IP-289 RID：可辨识性缺口（商掉观测等价 / 安全等价，而不是直接算熵）
def identifiability(q, equiv_obs, equiv_safe, alpha_star):
    rid_obs  = quotient_entropy(q, equiv_obs)
    safe_cls = safety_class(alpha_star, equiv_safe)
    rid_safe = 1.0 - mass(q, safe_cls)               # 安全判决不同的质量
    return rid_obs, rid_safe

# IP-290 RSC：切换证书（似然比 + 驻留 + 两阶段；无证书即角色违规）
class SwitchCertifier:
    def detect(self, llr, dwell, two_phase_id, pending_veto):
        if llr > TAU_LLR and dwell >= DWELL_MIN \
           and two_phase_id is not None and not pending_veto:
            return SwitchCert(dwell=dwell, llr=llr, two_phase=two_phase_id)
        return None                                  # 不认证 -> 不允许切换

# IP-291 RCC：声明–执行承诺（时态逻辑监视；返回违反见证）
class CommitmentMonitor:
    def check(self, declared, trajectory, beta_hat):
        # 例：G(!move_without_consent) U role_released
        for formula in declared.commitments:
            ok, witness = self.monitor.step(formula, trajectory, beta_hat)
            if not ok: return False, witness
        return True, None

# IP-292 DCR：灵巧接触角色图 + 角色条件力封闭 / 滑移
def role_conditioned_force_closure(G_c, alpha, mu, f_ext):
    constraints = {e: role_constraint(G_c.rho[e], alpha) for e in G_c.edges}
    return exists_internal_force(constraints, mu, f_ext)   # 摩擦锥 + 力平衡

def slip_evidence(tactile, alpha):
    return p_slip[tactile] if role_of(alpha) == 'pivot' else 0.0

# IP-293 RFA：歧义鲁棒 veto（最坏情形于可信指派集，非后验均值）
def role_safety_veto(q, b_alpha, a, G_c, mu, f_ext, delta=0.01):
    for alpha in credible_set(q, 1 - delta):
        if not safe(alpha, b_alpha[alpha], a):
            return VETO, alpha                       # 任一可信角色不安全 -> 否决
        if not role_conditioned_force_closure(G_c, alpha, mu, f_ext):
            return VETO, alpha
    return PASS, None

# IP-294 HOR：两阶段角色交接（prepare -> commit(epoch) -> retire）
class HandoverProtocol:
    def prepare(self, role, src, dst): self.shadow[role] = dst
    def commit(self, role, epoch):
        assert epoch > self.owner_epoch[role]       # 单调令牌，拒绝陈旧提交
        self.owner[role] = self.shadow.pop(role)
        self.owner_epoch[role] = epoch               # 原子单点切换
    def retire(self, role, src):
        assert self.owner[role] is not src
    # 不变式：<=1 owner；安全关键角色不允许 owner=None（分区 -> fail-safe hold）

# IP-295 RRB：角色反作用 + 角色预算 + 重声明阈值
def role_reflex_step(psi, a_robot, a_human, g, budget):
    psi2   = T(psi, g, role_robot=a_robot)
    drift  = d_role(a_robot, a_human)
    cost   = risk_delta(psi2) + LAM_D * drift + LAM_S * dist(psi2, PSI_SAFE).positive()
    if budget.spent + cost > budget.B_role:
        return psi, None, cost                       # 超预算 -> 冻结/重声明
    return psi2, cost, cost

# IP-296 RGA：角色 Goodhart 对偶（一致性必须配充分性）
def role_goodhart_alarm(consistency, adequacy, switch_precision, adapt_latency, tau_D):
    gap = max(abs(consistency - adequacy),
              abs(switch_precision - normalize(adapt_latency)))
    return gap > tau_D

# IP-297 AIC-ROLE / J_ROLE：证书
def J_ROLE(M):
    ok = (Valid_J_GAUGE(M) and M.rid_safe <= TAU_SAFE
          and M.rid_obs <= TAU_OBS and M.commitment_ok
          and all(M.switch_certs) and M.handover_ok
          and M.budget.spent <= M.budget.B_role
          and all(role_conditioned_force_closure(...) for _ in M.A_c))
    return Cert(valid=ok, ...)

# IP-298 ROLE 主闭环：角色层异步，绝不阻塞伺服
def ROLE_RAS_round(M, obs, tactile, audio, utterance):
    b_t = M.gauge.step(obs, audio)                   # R71 高频原样
    # --- 中频（10-20Hz）：角色指派 + 可辨识性 + 接触角色 ---
    if M.clock.due_role():
        q = M.rae.update(obs, tactile, M.proprio, M.role_history)
        rid_obs, rid_safe = identifiability(q, M.eq_obs, M.eq_safe, M.alpha_star)
        if rid_safe > TAU_SAFE or rid_obs > TAU_OBS:
            M.mode = 'GAUGE_ROLE_BLIND'              # 角色不可辨识 -> 保守
        cert = M.rsc.detect(M.role_llr, M.dwell, M.hor.two_phase_id, M.pending_veto)
        if cert is None and M.role_change_requested:
            M.mode = 'R71'                           # 未认证切换 -> 退回
    # --- 承诺与交接（事件触发）---
    ok, witness = M.cmm.check(M.declared, M.trajectory, M.beta_hat)
    if not ok:
        M.mode = 'SAFE_HOLD'; M.log(witness)         # 角色义务违反 -> 停
    if M.hor.pending: M.hor.step()
    # --- 角色安全否决（高风险接触动作前）---
    if M.mode in ('FULL',):
        verdict, bad = M.rfa.check(q, b_t, M.proposed_action, M.G_c, M.mu, M.f_ext)
        if verdict == VETO:
            M.proposed_action = M.fallback.safe_role_agnostic_action(bad)
    # --- 角色预算 / 重声明 ---
    if M.role_drift > TAU_REDECLARE:
        M.redeclare(M.declared, reason='drift')      # 主动重协商，不沿用旧声明
    # --- 高频控制（R71 原样，使用角色条件化后的动作/信念）---
    k, lam, U, J = M.gauge.execute(M.proposed_action, b_t)
    return k, lam, U, J_ROLE(M)
```

## 3. 推导

**引理 28（标签对称下 H[α] 既非必要也非充分）** 设 G 为保持观测似然的角色重贴标签群，q 为后验。若 q 在轨道上均匀，则 H[q] = H[q/G] + log|G|；一般地 H[q] ≥ H[q/G]，超出部分是**不含信息的标签熵**。因此用 H[α] 衡量角色不确定度会系统性高估良性对称歧义（两只同构手指都可当支点）。反过来，存在 q 集中于单一指派 α̂、H[q]≈0，但 α̂ 与真值在 ≡_safe 下不等价，此时 RID_safe≈1：**后验尖 ≠ 角色对**。故必须用商空间熵与安全等价类质量，而不是裸熵。系：R71 的 H[b_t] 在角色维度上不可用作「知道谁是谁」的度量。

**引理 29（切换检测的驻留–延迟下界）** 把角色切换建模为变点：切换前后角色条件观测分布每步 KL 散度为 D_KL。对假切换率 α 与漏切换率 β，任何检验的期望检测延迟满足下界 Δτ ≥ (1−α)·log(1/β)/D_KL（Lorden/Weinstein–Weiss 型变点下界）。故「零驻留、即时切换」若不接受高假切换率，就必须接受长延迟；若既要求低延迟又要求低假切换，只能提高 D_KL（更多主动感知）。**RSC 的 dwell 与 ΔLLR 不是工程阻尼，而是这条下界的显式化；安全关键交接必须两阶段，因为单次证据不足。** 系：在触觉稀疏时，最诚实的做法是「不认证切换 + 冻结」，而不是「先切了再说」。

**引理 30（一致 ≠ 充分；冻结角色是完美一致的错误）** 设一致性 C = 1 − TV(执行角色分布, 声明角色)，充分性 A = 期望任务成功。存在策略 π_freeze 使 C(π_freeze)=1 而 A(π_freeze)→0（需要角色切换的任务上）。更强地，对任意声明角色 a，存在世界 w 使「坚持 a」不安全；故仅最大化 C 的风险无界。因此一致性只能是**带充分性下界的约束**，不能作为单一目标。系：这正是 R71 的 Goodhart 结构在角色维度的重演，且更难发现，因为「一致」听起来就是在保护安全；RGA 的 antipair 是强制补丁。

**引理 31（歧义鲁棒否决 vs 后验均值）** 设可信集 𝔄^c 中 α_safe 质量 0.95、α_unsafe 质量 0.05，α_unsafe 导致灾难损失 L。后验期望风险为 0.05L，对阈值 τ 在 L ≤ 20τ 时仍通过；但最坏情形风险为 L。对安全关键动作，正确对象是**集合级否决** V_role=1[∃α∈𝔄^c 不安全]，而非期望风险。代价是保守性，其量级由 𝔄^c 的质量与几何决定；RID_safe→0 时退化为 MAP 安全。系：R71 的 ECE/校准保证的是「概率对」，不保证「概率质量所在的那个角色是安全的」；这正是 RFA 必须取最坏情形的原因。

**引理 32（交接的所有权不变式）** 在可靠、全序的 commit 消息与单调 epoch 令牌下，prepare→commit→retire 满足：任一角色 |owner| ≤ 1（唯一所有权），安全关键角色 |owner| ≥ 1（无无主窗口）。反例：release-then-acquire 至少在一个 RTT 内 |owner|=0；acquire-then-release 至少在一个 RTT 内 |owner|=2。分区下若要求双主不可能且无主不允许，则只能 fail-safe hold（保持最后 owner 并冻结）——这是原子提交 / 双将军不可能性在角色交接上的实例：**不可能在分区下同时保证安全（无无主/无双主）与活性（总能推进）**。系：角色层必须显式声明牺牲活性，而不是让「谁先到谁当主」隐式决定。

**引理 33（角色漂移的有界性与重声明必要性）** 设人的角色/信任更新 T_role 对机器人执行角色的偏差 Lipschitz 常数为 L_R。声明–执行偏差 e_t 近似满足 e_{t+1} ≈ (1−η(1−L_R))e_t + noise。当 L_R<1 时漂移有界；当 L_R≥1（人越让步、机器人越主导、声明越失真）时偏差可增长，声明角色逐渐变成「历史遗迹」。因此角色一致性**不是静态属性，而是需要主动重声明的维护过程**；RRB 把 drift 纳入预算并在超阈时强制重协商。系：R71 的信任预算只计量「打扰」，未计量「角色被我们演歪」。

**定理 23（严格包含链）** 在 A106–A110（角色本体正确且版本可检、指派可辨识或可退回角色无关策略、切换检测满足引理 29 的界、交接可靠全序、反作用 T_role Lipschitz）下：ROLE-RAS 在单实体、单平凡角色、静态接触、RID=0、声明与执行无区别、B_role=∞ 时逐指令等于 GAUGE-RAS；再由 R71 定理 20 退化 BELIEF ⊂ FLUID ⊂ R68。**安全侧永不弱于 R71；效率侧只在「角色可辨识且契约可兑现」时获得。**

**定理 24（角色条件风险界）** 若一次执行通过 J_ROLE，则 ∀α∈𝔄^c 角色条件安全与角色条件力封闭成立，承诺未违反、交接不变式成立、角色预算未超。故风险 ≤ ε_cert(J_GAUGE) + ε_role(RID_safe, 本体失配, 切换延迟)。若任一门控失败，则退回角色无关的保守 GAUGE/R71 策略或 safe-hold，其风险由 R71 定理 21 保证。因此 ROLE-RAS 的期望风险 ≤ GAUGE-RAS。**全部重量落在「本体正确」与「指派可辨识」上**——这正是 RID/RSC/TCHAIN-role 存在的理由，也是本轮最大风险所在。

**定理 25（切换/交接的强安全与条件活性）** 在 RSC 的证书条件（ΔLLR、dwell、两阶段、无未决否决）与 HOR 的 epoch 令牌下：不存在未认证的角色切换；不存在双主或无主窗口；一次任务内的切换次数受 B_role 限制。安全性**无条件**成立（含分区，因 fail-safe hold）。活性（任务继续推进）只在「最终出现可认证切换或人类显式重声明」的公平性假设下成立；若无，则系统安全停机而非不安全推进——与引理 32 的不可能性一致。**这把「角色一致性」从一个模糊的美德，变成一条可证明的、会以活性换取安全的状态机。**

## 6. 次级风险与缓解

1. **角色本体错误 / 本体投毒** → 本体版本化 + 离线专家审计 + 在线只读；本体失配触发 `GAUGE_ROLE_BLIND` 回退；E341/E356。
2. **角色不可辨识（触觉稀疏、对称歧义）** → RID 双门控 + 主动感知（探索角色）消歧；不可消歧则禁止高风险动作，绝不把 MAP 当真值；E343/E344/E351。
3. **事后重贴标签 / 追溯篡改** → 声明先于动作的因果时间戳 + 冻结历史哈希 + 密封审计（继承 R71 SEAL）；E356。
4. **冻结角色 / 过度保守导致任务失败** → 一致性只作约束、配充分性反指标 RGA；切换预算允许适配；E348/E355。
5. **交接分区下活性归零** → 显式 fail-safe hold + 人类重声明通道；把「牺牲活性」写进契约而不是假装能两者兼得；E353。
6. **角色漂移 / 谄媚螺旋** → 漂移预算 + 超阈强制重声明 + 长期人机实验；E347/E354。
7. **实时预算被角色层击穿** → 异步中频 + 事件触发交接；角色层永不进伺服快路径；E359。

## 7. 本轮最大风险（一句话）

**角色一致性最危险的地方，是它把安全问题从「状态估错」悄悄换成了「角色被自洽地讲错」：若角色本体本身有误、或接触角色在现有触觉下不可辨识，系统就会用一个事后可重贴标签、永远「一致」的角色历史去自证安全——灵巧手在错误的接触角色下「自洽地」违反力封闭，而证书上写满了角色一致。**

## 2. 形式化定义（要点版）

**定义 349（总览与四不变式）** ROLE-RAS 继承 GAUGE 全部组件（† 升级），新增角色层（ROL/RAE/RID/RSC/RCC/DCR/RFA/HOR/RRB/RGA）。四不变式：(i) 零学习写操作；(ii) 角色完整性（本体/后验/RID/切换证书/τ_role 齐全，否则不得进否决）；(iii) 歧义鲁棒非补偿安全（∀α∈𝔄^c 取最坏，性能不可补偿）；(iv) 一致–充分分离（一致性是约束，需配充分性反指标）。

**定义 350（角色本体）** 角色类型化并带义务/权限/不变式；任务角色（主导/助手/观察/安全监督）、接触角色（pivot/slider/stabilizer/explorer/release/load-bearing）、社会角色（principal/agent/peer）。角色可组合但须通过本体类型检查。**本体是「能做什么/必须做什么/禁止做什么」的可证伪契约。**

**定义 351（角色指派）** α_t: E_t ⇀ ℛ 为部分单射，满足能力类型约束；𝔄_t 为可容许指派；G 为观测下等价的标签置换群。α_t 不是世界状态，而是对世界状态的关系性解释；同一 s_t 在不同 α 下安全含义不同。

**定义 352（角色条件模型）** q_t(s,α) ∝ p(o|s,α)p(s|α)p(α|A_{0:t−1})；角色决定约束集/承载边/可动指。**角色改变模型结构，而非仅改变噪声参数。**

**定义 353（RID）** RID_obs = H[q/≡_obs]；RID_safe = 1 − q([α*]_{≡_safe})。标签对称 ⇒ H[α] 大但 RID 小（良性）；后验尖但贴在安全不等价类 ⇒ H[α] 小但 RID_safe 大（自信地错角色）。R71 的 H[b_t] 对二者无感。

**定义 354（角色一致后验）** q^R ∝ q·1[α∈𝔄_consistent]·1[α 与切换证书相容]；高风险决策不取后验均值，进入定义 358 的集合级否决。

**定义 355（切换证书）** 切换需 ΔLLR 超阈 + dwell≥dwell_min + 两阶段交接 + 无未决否决；无证书即角色违规。δ_false/δ_missed 为假/漏切换界；dwell 是引理 29 变点下界的显式化。

**定义 356（承诺一致性）** 声明角色带时态逻辑承诺 K（如 `G(¬move_without_consent) U role_released`）；ρ_K(ξ) 判定轨迹是否满足并给见证；一致性还要求声明与自模型能力、权限不矛盾。drift=d(α^decl,α^act)。

**定义 357（灵巧接触角色 DCR）** G_c=(V_c,E_c,ρ_c)；角色条件力封闭 FC(G_c,α,μ,f) 在 α 决定的约束集上存在满足摩擦锥与力平衡的内力；滑移模型依赖角色，incipient slip 是 pivot→slider 的证据。**力封闭是手–物系统在某个角色指派下的属性。**

**定义 358（歧义鲁棒否决 RFA）** V_role(t,a)=1[∃α∈𝔄^c: ¬Safe(α,b^α,a) ∨ ¬FC(G_c,α)]。任一可信指派不安全即否决，非后验均值；RID→0 退化为 MAP 安全。低风险可用带非负歧义惩罚的期望风险。

**定义 359（交接协议 HOR）** prepare（就绪/影子）→ commit（epoch 令牌原子切换）→ retire（释放）。不变式：安全关键角色 ≤1 owner 且无无主窗口；分区默认 fail-safe hold（保安全、牺牲活性）。release-then-acquire 有无主窗口，acquire-then-release 有双主窗口。

**定义 360（角色反作用 RRB）** ψ_{t+1}=T(ψ_t,g,ρ_robot,α^robot)，α^human_{t+1}=T_role(α^human,α^robot,ψ)；角色预算 Σ[c_switch+λ_d·drift]≤B_role；drift>τ_redeclare 必须主动重声明。**不能单方面「演成」另一个角色而不更新契约。**

**定义 361（角色 Goodhart 对偶 RGA）** 一致性↔充分性、声明保真↔独立承诺审计、切换精确率↔适配延迟、角色稳定性↔响应性；D_role 超阈 ⇒ 角色指标本次失效。**「一致」永远不能单独作为放行理由。**

**定义 362（角色证据纪律）** 安全关键角色需实体身份 + 功能角色 + 声明三类证据，且至少一个正交通道不矛盾；单模态不得定案；跨模态「过度一致」也要警惕共谋欺骗。延伸 R71 定义 343。

**定义 363（角色追溯）** τ_role=(ontology_ver, assignment_history_hash, switch_cert_ids, commitments_hash, evidence_sources, timestamp, validity_interval)；缺失/过期即「未验证角色」，不得进否决。**没有角色溯源，就没有角色否决。**

**定义 364（AIC-ROLE）** ℰ_ROLE=ℰ_GAUGE×ℰ_role；ℰ_role={实体身份伪装、接触角色误配、事后重贴标签、切换 gaming、本体投毒、persona 漂移/谄媚、交接双主/无主攻击、跨模态角色共谋}。

**定义 365（J_ROLE）** Valid ⇔ Valid(J_GAUGE) ∧ RID_safe≤τ_safe ∧ RID_obs≤τ_obs ∧ 承诺未违反 ∧ 切换证书有效 ∧ ∀α∈𝔄^c FC 通过 ∧ 交接不变式成立 ∧ 角色预算未超。

**定义 366（流水线与严格包含）** 高频伺服（R71 原样）／中频角色检查（10–20Hz）／低频重估与重声明（1–5Hz）+ 事件触发 RSC/HOR/RCC；角色层不进伺服快路径。单实体、单平凡角色、接触静态、RID=0、声明=执行、B_role=∞ ⇒ 逐指令等于 GAUGE-RAS ⇒ BELIEF ⇒ FLUID/R68。

# IP-287 ROL：角色本体（类型化、版本化、在线只读）
class RoleOntology:
    def __init__(self, roles, leq, obligations, permissions, invariants, ver):
        self.R, self.leq, self.Obl, self.Perm, self.Inv, self.ver = \
            roles, leq, obligations, permissions, invariants, ver
    def admissible(self, task): return [r for r in self.R if task.requires(r)]
    def typecheck(self, composite): return all(self.Inv[r](composite) for r in composite)

# IP-288 RAE
class RoleAssigner:
    def update(self, obs, tactile, proprio, history):
        self.q = self.filter.step(obs, tactile, proprio, history)
        return self.q
    def credible_set(self, q, mass=0.99): return min_mass_set(q, mass)

# IP-289 RID
def identifiability(q, equiv_obs, equiv_safe, alpha_star):
    return (quotient_entropy(q, equiv_obs),
            1.0 - mass(q, safety_class(alpha_star, equiv_safe)))

# IP-290 RSC
class SwitchCertifier:
    def detect(self, llr, dwell, two_phase_id, pending_veto):

           and two_phase_id is not None and not pending_veto:
            return SwitchCert(dwell=dwell, llr=llr, two_phase=two_phase_id)
        return None

# IP-291 RCC
class CommitmentMonitor:
    def check(self, declared, trajectory, beta_hat):
        for f in declared.commitments:
            ok, witness = self.monitor.step(f, trajectory, beta_hat)
            if not ok: return False, witness
        return True, None

# IP-292 DCR
def role_conditioned_force_closure(G_c, alpha, mu, f_ext):
    constraints = {e: role_constraint(G_c.rho[e], alpha) for e in G_c.edges}
    return exists_internal_force(constraints, mu, f_ext)

# IP-293 RFA
def role_safety_veto(q, b_alpha, a, G_c, mu, f_ext, delta=0.01):
    for alpha in credible_set(q, 1 - delta):
        if not safe(alpha, b_alpha[alpha], a): return VETO, alpha
        if not role_conditioned_force_closure(G_c, alpha, mu, f_ext): return VETO, alpha
    return PASS, None

# IP-294 HOR
class HandoverProtocol:
    def prepare(self, role, src, dst): self.shadow[role] = dst
    def commit(self, role, epoch):
        assert epoch > self.owner_epoch[role]
        self.owner[role] = self.shadow.pop(role); self.owner_epoch[role] = epoch
    def retire(self, role, src): assert self.owner[role] is not src

# IP-295 RRB
def role_reflex_step(psi, a_robot, a_human, g, budget):
    psi2 = T(psi, g, role_robot=a_robot)
    cost = risk_delta(psi2) + LAM_D * d_role(a_robot, a_human) \
           + LAM_S * dist(psi2, PSI_SAFE).positive()
    if budget.spent + cost > budget.B_role: return psi, None, cost
    return psi2, cost, cost

# IP-296 RGA
def role_goodhart_alarm(consistency, adequacy, switch_precision, adapt_latency, tau_D):
    return max(abs(consistency - adequacy),
               abs(switch_precision - normalize(adapt_latency))) > tau_D

# IP-297 J_ROLE / IP-298 主闭环
def J_ROLE(M):
    return Cert(valid=(Valid_J_GAUGE(M) and M.rid_safe <= TAU_SAFE
                       and M.rid_obs <= TAU_OBS and M.commitment_ok
                       and all(M.switch_certs) and M.handover_ok
                       and M.budget.spent <= M.budget.B_role
                       and all(role_conditioned_force_closure(...) for _ in M.A_c)))

def ROLE_RAS_round(M, obs, tactile, audio, utterance):
    b_t = M.gauge.step(obs, audio)                       # R71 高频原样
    if M.clock.due_role():                               # 中频角色审计
        q = M.rae.update(obs, tactile, M.proprio, M.role_history)
        rid_obs, rid_safe = identifiability(q, M.eq_obs, M.eq_safe, M.alpha_star)
        if rid_safe > TAU_SAFE or rid_obs > TAU_OBS:
            M.mode = 'GAUGE_ROLE_BLIND'
        cert = M.rsc.detect(M.role_llr, M.dwell, M.hor.two_phase_id, M.pending_veto)
        if cert is None and M.role_change_requested: M.mode = 'R71'
    ok, witness = M.cmm.check(M.declared, M.trajectory, M.beta_hat)
    if not ok: M.mode = 'SAFE_HOLD'; M.log(witness)      # 承诺违反 -> 停
    if M.hor.pending: M.hor.step()
    if M.mode == 'FULL':
        verdict, bad = M.rfa.check(q, b_t, M.proposed_action, M.G_c, M.mu, M.f_ext)
        if verdict == VETO: M.proposed_action = M.fallback.safe_role_agnostic_action(bad)
    if M.role_drift > TAU_REDECLARE: M.redeclare(M.declared, reason='drift')
    k, lam, U, J = M.gauge.execute(M.proposed_action, b_t)
    return k, lam, U, J_ROLE(M)

## 4. 推导

**引理 28（标签对称下 H[α] 既非必要也非充分）** 若 q 在 G-轨道上均匀，H[q]=H[q/G]+log|G|；一般 H[q]≥H[q/G]，超出部分是不含信息的标签熵。故裸熵高估良性对称歧义；反过来存在 H[α]≈0 但 RID_safe≈1（MAP 贴在安全不等价类）。**后验尖 ≠ 角色对；必须用商空间熵与安全等价类质量。**

**引理 29（切换检测驻留–延迟下界）** 变点前后每步 KL 为 D_KL，对假切换 α、漏切换 β，期望延迟 Δτ ≥ (1−α)log(1/β)/D_KL（Lorden/Weinstein–Weiss 型）。故「零驻留即时切换」要么高假切换，要么长延迟；两者都要低只能提高 D_KL（主动感知）。**RSC 的 dwell/ΔLLR 是这条下界的显式化；证据不足时最诚实的动作是「不认证 + 冻结」。**

**引理 30（一致 ≠ 充分）** 存在 π_freeze 使 C=1 而 A→0（需切换的任务）；对任意声明角色 a，存在世界 w 使坚持 a 不安全，故仅最大化 C 的风险无界。一致性只能是带充分性下界的约束。**这是 R71 Goodhart 在角色维度的重演，且更难发现，因为「一致」听起来就在保护安全。**

**引理 31（歧义鲁棒否决 vs 后验均值）** 若 𝔄^c 中 α_safe 质量 0.95、α_unsafe 0.05 且导致灾难损失 L，后验期望风险 0.05L 可能通过阈值，而最坏风险为 L。安全关键动作的正确对象是集合级否决 V_role=1[∃α∈𝔄^c 不安全]，非期望风险；保守代价由 𝔄^c 质量/几何决定，RID_safe→0 退化为 MAP 安全。**ECE 保证概率对，不保证概率质量所在的角色安全。**

**引理 32（交接所有权不变式）** 可靠全序 commit + 单调 epoch 下，prepare→commit→retire 满足 ≤1 owner 且安全关键角色 ≥1 owner。release-then-acquire 至少一个 RTT 无主；acquire-then-release 至少一个 RTT 双主。分区下同时要求无无主与无双主只能 fail-safe hold——原子提交/双将军不可能性在角色交接上的实例。**必须显式牺牲活性。**

**引理 33（角色漂移有界性与重声明必要性）** 若 T_role 对执行角色偏差 Lipschitz 常数 L_R，则 e_{t+1}≈(1−η(1−L_R))e_t+noise：L_R<1 有界；L_R≥1（人越让步、机器人越主导、声明越失真）可增长。角色一致性是需主动重声明的维护过程，RRB 将 drift 纳入预算并超阈重协商。**信任预算只计量「打扰」，未计量「角色被演歪」。**

**定理 23（严格包含链）** 在 A106–A110（本体正确可检、指派可辨识或可退回角色无关、切换满足引理 29、交接可靠全序、T_role Lipschitz）下：ROLE-RAS 在单实体/单平凡角色/静态接触/RID=0/声明=执行/B_role=∞ 时逐指令等于 GAUGE-RAS；再由 R71 定理 20 退化 BELIEF⊂FLUID⊂R68。安全侧不弱于 R71；效率侧只在角色可辨识且契约可兑现时获得。

**定理 24（角色条件风险界）** 通过 J_ROLE ⇒ ∀α∈𝔄^c 角色安全与 FC 成立、承诺未违反、交接不变式成立、预算未超 ⇒ 风险 ≤ ε_cert(J_GAUGE)+ε_role(RID_safe, 本体失配, 切换延迟)。任一门控失败 ⇒ 退回角色无关保守 GAUGE/safe-hold，风险由 R71 定理 21 保证。故期望风险 ≤ GAUGE。**全部重量落在「本体正确」与「指派可辨识」上。**

**定理 25（切换/交接强安全与条件活性）** 在 RSC 证书条件与 HOR epoch 令牌下：无未认证切换、无双主、无无主窗口；切换次数受 B_role 限制。安全性无条件成立（含分区，因 fail-safe hold）。活性只在「最终出现可认证切换或人类显式重声明」的公平性假设下成立；否则安全停机而非不安全推进，与引理 32 的不可能性一致。**一致性从模糊美德变成可证明、以活性换安全的状态机。**

## 7. 次级风险与缓解

1. **角色本体错误 / 投毒** → 版本化 + 离线专家审计 + 在线只读；失配回退 `GAUGE_ROLE_BLIND`；E341/E356。
2. **角色不可辨识（触觉稀疏/对称歧义）** → RID 双门控 + 主动探索消歧；不可消歧则禁高风险动作，绝不把 MAP 当真值；E343/E344/E351。
3. **事后重贴标签 / 追溯篡改** → 声明先于动作的因果时间戳 + 冻结历史哈希 + 密封审计；E356。
4. **冻结角色 / 过度保守** → 一致性只作约束 + 充分性反指标 RGA；切换预算允许适配；E348/E355。
5. **交接分区下活性归零** → 显式 fail-safe hold + 人类重声明通道；把「牺牲活性」写进契约；E353。
6. **角色漂移 / 谄媚螺旋** → 漂移预算 + 超阈强制重声明 + 长期人机实验；E347/E354。
7. **实时预算被击穿** → 异步中频 + 事件触发交接；角色层永不进伺服快路径；E359。

## 8. 本轮最大风险（一句话）

**角色一致性最危险的地方，是它把安全问题从「状态估错」悄悄换成了「角色被自洽地讲错」：若角色本体本身有误、或接触角色在现有触觉下不可辨识，系统就会用一个事后可重贴标签、永远「一致」的角色历史去自证安全——灵巧手在错误的接触角色下「自洽地」违反力封闭，而证书上写满了角色一致。**
