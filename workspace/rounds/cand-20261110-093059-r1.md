# 第 43 轮（新循环第 3 轮） · Cert-Mix × Cert-MW：给证书飞轮装两台调速器——数据配方（Mix）与证书中间件（Middleware）（四层架构 v8）

> 承接第 42 轮 v19（SCV × CKB × ECR）。第 42 轮自陈最大风险是「仿真偏差累积 + 检索幻觉」：飞轮会产数据、会检索、会部署，但它**不控制数据的成分**，也**不掌控证书在运行时的流动路径**。本轮灵感词「数据配比」「中间件」恰好补这两处命门：**数据配比**把「喂给仿真/知识库/蒸馏的数据」从"随手采"变成"按配方配"，用一条可拟合的「混合定律」在 soundness（不漏报）与 tightness（不过保守）之间做显式优化，并用重要性采样把稀有失效从"测不到"变成"测得准"；**中间件**把证书从"跑在系统之上的离线制品"下沉为"随消息流动的一等公民"——每条消息带「证书胶囊」，每一跳核对 rely-guarantee 契约，QoS 降级映射为证书模式降级。二者合起来：**中间件是账本，数据配比是控制器**；账本提供带归因的 (状态, 证书, 结果, 上下文) 四元组，控制器据此重配数据预算，飞轮从「能转」升级为「转得准、转得省、转得可追责」。

## 0. 直觉与动机

**灵感 1（数据配比 → 证书的「营养学」）**：第 42 轮的域随机化是"大锅饭"：D_sim 里 nominal、稀有感噪、极端摩擦、执行器故障按固定比例混合，蒸馏/标定/检索都用同一锅数据。这暗含一个错误假设——"数据越多越好"。真实的证书质量有两个方向相反的失效：**nominal 过量** → 边际拟合得很紧、但盲区没被覆盖，证书"自信地漏报"；**对抗/极端过量** → 覆盖很全、但边际被压得过低，证书"安全地不可用"（正是第 41 轮的可用性崩塌）。所以数据配比是证书质量的**第一性变量**，不是超参数。直觉上像营养学：不同数据源是不同营养素，配方决定"既不营养不良（漏掉稀有失效）也不营养过剩（过度保守）"。进一步，既然要估计的是稀有事件概率（violation），数据配比本质是在设计一个**重要性采样提议分布**——同一个配比既训练证书、又评估证书，这里藏着"自评自"的估计偏差，必须显式拆开（见定义 39 的双通道设计）。

**灵感 2（中间件 → 证书作为一等消息与逐跳契约）**：第 42 轮的证书对象住在 L4 飞轮/L3 规划里，但机器人真正跑在 ROS2/DDS 消息总线上：感知→融合→规划→控制之间是异步、会丢帧、会有 deadline。证书若不能进入消息平面，端到端 soundness 就只是"设计时的假定"，而非"运行时的保证"。中间件的直觉是：给每条消息挂一个**证书胶囊**（证书哈希、有效域键、阈值、签发/过期时间、来源链、模式位），中间件在每一跳做三件事——验票据（未过期、哈希一致、状态在有效域内）、验契约（上游 post 是否 refine 下游 pre）、验时序（是否在 deadline 内）。这把"一个全局证书定理"拆成"一串可局部验证的 hop 契约"，既能在故障时精准定位哪一跳破了契，又天然产出带归因的遥测账本。QoS 的 reliability/deadline/liveliness 不再是调参，而是**证书模式的下采样**：可靠性降级 → 证书档位降级 + 更保守守卫；deadline 逼近 → 提前进入单调保守降级。

**灵感 3（耦合：账本—控制器的数据经济）**：中间件账本记录的是"在哪个证书下、哪一跳、因为什么失败"，这正是数据配比最缺的**归因信号**。没有它，配比优化只能在仿真里闭门造车；有了它，配比可以按"哪种数据源的边际收益最高"来花预算（离线仿真 / 实机标定 / 对抗生成 / 反例重放）。于是闭环升级为：**CMW 观测 → CDM 重配 → SCV/CKB 再生产 → CMW 再部署**。第 42 轮是"数据→证书"的单向飞轮，本轮加入"归因→配比"的负反馈，使飞轮具备**预算自适应**能力。

## 1. 形式化定义（增量：定义 38–45）

**定义 38（证书数据配方）**：数据源集合 S = {S_nom, S_rare, S_real, S_cex, S_adv}，分别对应标称仿真、稀有域随机化、实机标定、反例重放、对抗生成。配方 m = (w_1,…,w_K) ∈ Δ^{K−1}（单纯形），采样数据集 D(m) = ⨄_i StratifiedSample(S_i, w_i·N)。证书学习/标定算子 C(m) = L(D(m))，输出 (θ(m), L_m(m), T_hold(m), C_sim(m))。**配方是可审计对象**：hash(m) 写入证书 provenance。

**定义 39（配方—证书响应面与双通道估计）**：定义三目标响应面 Φ(m) = (δ(m), τ(m), κ(m))，其中 δ 为 soundness gap（真实分布下 P(m_real < m_lo)，即漏报概率），τ 为 tightness（E[保守余量]，越大越保守越不可用），κ 为数据成本。**混合定律假设（H-Mix）**：在支撑覆盖充分时，
δ(m) ≈ δ_∞ + Σ_i a_i w_i^{−β_i}（边际收益递减），τ(m) ≈ τ_0 + Σ_i b_i w_i（越对抗越保守），a_i, b_i, β_i > 0。
δ 必须用**双通道**估计：训练通道用配方 m 采样，评估通道用与训练不共享随机种子的留出配方 m_hold 采样，且以重要性采样修正到真实分布 p：
δ̂(m) = (1/n) Σ_{x∼q_m} [p(x)/q_m(x)]·1[violation(x)]，
并要求有效样本量 ESS = (Σω)²/Σω² ≥ ESS_min，否则该估计作废（防"自评自"偏差）。

**定义 40（配比优化问题与鲁棒版）**：名义问题 m* = argmin_{m∈Δ} τ(m) s.t. δ(m) ≤ δ_max, κ(m) ≤ B, D_KL(m‖m_ref) ≤ ε_mix（信任域，防止配方漂移导致不可复现）。鲁棒版在配方不确定集 U(m) = {m' : ‖m'−m‖_1 ≤ ρ} 上求 min_m max_{m'∈U(m)} τ(m') s.t. 同约束，即对"配方自身被估错"也保 sound。

**定义 41（证书胶囊）**：消息 msg 携带胶囊 cap = (h_cert, key(x), θ_vec, t_issue, t_exp, prov_chain, mode, sig)，h_cert 为证书内容哈希，key(x) 为 L0 查表键，prov_chain 为 (git_commit, sim_config_hash, recipe_hash, 硬件版本) 链，mode ∈ {T-1, T0, T1, T2, SAFE}，sig 用总线密钥签名防篡改。胶囊定长、可零拷贝 CDR 序列化。

**定义 42（逐跳 rely-guarantee 契约与组合可靠性）**：hop h = (pre_h, post_h, C_h, T_h)，pre/post 为状态/消息谓词，C_h 为保障该 hop 的证书，T_h 为其 WCET 预算。中间件在投递时校验：(i) cap.t_exp ≥ now（新鲜）；(ii) key(x) ∈ C_h.ValidRegion（域内）；(iii) post_{h_i} ⇒ pre_{h_{i+1}}（契约精化）；(iv) C_h 规定的 WCET 满足 deadline。若 hop 链 h_1…h_n 全部通过，则端到端失败概率满足并集界 P_fail^e2e ≤ Σ_i P_fail(h_i) + P_stale，其中 P_stale 由过期/时钟漂移独立界出。**命题（链式精化）**：若每跳 sound 且契约精化成立，则端到端不变式沿链保持（标准 assume-guarantee 归纳）。

**定义 43（QoS—证书模式映射）**：QoS 配置 q = (deadline, reliability, liveliness, latency_budget) 映射到证书档位与降级动作 M(q)：若剩余时延 < T_verify + T_hold 则强制 SAFE；若 reliability < r_min 或 liveliness 超时则单调降档（T2→T1→T0→T-1→SAFE）；映射须满足可调度条件 Σ_h C_h/T_h ≤ U_max 且 T_verify ≤ min_h deadline_h。映射表随证书一起版本化。

**定义 44（混合调速器）**：状态 s_t = (δ̂_t, τ̂_t, 剩余预算 B_t, 账本归因统计)，控制律 m_{t+1} = Π_Δ(m_t − η ∇_m [τ̂(m_t) + λ·max(0, δ̂(m_t)−δ_max)] )，Π_Δ 为信任域投影。**势函数** V_t = τ̂_t + λ·max(0, δ̂_t−δ_max)；若响应面在 m_t 邻域局部正确且步长 η 满足标准条件，则 E[V_{t+1}] ≤ V_t − c·‖∇V‖²（Lyapunov 型下降）。

**定义 45（证书账本与反事实归因）**：账本 L = {(t, hop, msg_id, cap, outcome, env_ctx)}。归因器 A 估计"若该 hop 使用数据源 i 重训，失败率变化"的反事实效应：ATE_i = E[Y | do(recipe←m+e_i)] − E[Y | do(recipe←m)]。归因不确定性 σ_i 以自助法估计；当 σ_i > σ_max 时调速器**冻结**该数据源权重（拒绝在归因不可信时优化，防自指放大）。

## 2. 三大产出设计（增量 IP-57/58/59 + 升级 IP-54/55/56/51/52/53/49/50/45/47）

### 2.1 IP-57 CERT-DATA-MIXER（证书数据配方器 CDM）
1. **分层源管理**：每个数据源按 (任务指纹 φ, 失效标签, 边际分位桶) 三层分桶；跨桶强制最小配额，杜绝"稀有桶被大桶淹没"。
2. **混合定律在线拟合**：对 τ、δ 用单调约束的对数-对数回归 / 单调 GP 拟合（H-Mix），给出 per-source 边际收益 ∂δ/∂w_i；拟合残差超阈即标注"响应面不可信"。
3. **配比优化**：投影梯度 / 注水算法解定义 40；信任域 ε_mix 保证可复现；每轮输出 recipe_hash 入证书 provenance。
4. **主动采集**：以"单位成本期望 δ 下降"为采集值（expected violation reduction per dollar），在四源间分配下一批预算；反例源优先进入稀有事件重要性采样提议。
5. **留出集审计**：训练/评估双通道隔离；每轮在 m_hold 上重估 δ̂，与训练通道差异 > 2σ 则判为过拟合配方并回退 m_ref。

### 2.2 IP-58 CERT-MIDDLEWARE（证书中间件 CMW / CCM）
1. **胶囊总线**：发布侧中间件拦截器自动封装 cap；订阅侧零拷贝解析；提供 `attach/detach/verify` 三原语，胶囊格式定长、schema 版本化。
2. **契约注册表**：编译期从 CAR 转移表导出每 hop 的 (pre, post, C_h, T_h)，静态检查 post⇒pre；运行期监控动态违约。
3. **QoS 映射状态机**：DDS QoS 事件 → 模式位 → 单调降档；降档不可逆直到重新通过验证（防抖）。
4. **遥测账本**：按定义 45 记录带归因的四元组；提供 (a) 漂移统计 S_t，(b) 归因输入，(c) 审计回放三段查询。
5. **故障注入与 hop 单测**：可在仿真/回放中对单跳注入丢帧、延迟、篡改胶囊，验证组合可靠性上界。

### 2.3 IP-59 MIX-GOVERNOR（混合调速器 MG）
1. **账本驱动的响应面校准**：把 CMW 的实机失败按 hop/环境/配方切片，在线校正 H-Mix 的 δ 项。
2. **预算分配器**：把总预算 B 在 {仿真、实机标定、对抗生成、反例重放} 间按边际收益注水；设最小实机标定配额（防纯仿真漂移）。
3. **稳定性护栏**：信任域 + 迟滞 + 归因不确定时冻结；偏移触发冷却期复用第 42 轮 T_cool。
4. **可解释输出**：每轮产出"为什么改配方"的归因报告（哪源边际收益最高、哪源置信度不足）。

## 4. 实验设计（E87–E94 硬门槛，承接 E79–E86）

| 实验 | 指标 | 门槛 |
|---|---|---|

| E88 配比优化有效性 | 同预算下 δ、τ vs 固定均匀配比 | δ ≤ 1e−3 且 τ 改善 ≥ 20%；双通道差异 < 2σ |

| E91 QoS 降档正确性 | deadline 逼近时进入 SAFE 的正确率；静默过期次数 | ≥ 99.99%；0 次 |
| E92 数据经济闭环 | 3 轮重配后 Nominal 占比、漏报率、预算节省 | ≥ 85%；≤ 1e−3；预算降 ≥ 30% |
| E93 胶囊完整性与版本一致 | 篡改/旧版本/跨硬件 capsule 拒绝率 | 100% |
| E94 长时程 CMW 运行 | 100 小时：不安全事件、Nominal、hop 违约、账本漂移 | 0 起；≥ 80%；违约 < 0.1%/hop；漂移触发 < 5/天 |

回退：E87 拟合失败 → 退回均匀配比 + 只保留稀有桶最小配额；E88 无改善 → 关闭 CDM，锁定 recipe_hash；E89 开销超预算 → 胶囊仅保留 h_cert+expiry（瘦身），验签降到抽样；E90 检出不足 → 关闭 hop 组合，回退第 42 轮全局证书；E91 降档失效 → 总线旁路，双态 SafeStop。

## 5. 本轮最大风险

**一句话**：把证书质量绑在「数据归因」与「时序耦合」两根新支柱上——若中间件账本对失败的归因存在系统性偏差（例如把延迟引起的失败错记到感知数据头上），配比优化会放大错误数据源，形成「越优化越自信、越自信越漏报」的自指闭环；而胶囊注入拉长消息路径，本身又可能成为新的 deadline 违约源，使安全开销反向制造不安全。这是本轮方案的最大风险，必须以 E88 的留出集双通道审计与 E89 的时延预算红线双重设防。

# 第 43 轮产物 · 创新点清单 v20：Cert-Mix × Cert-MW——数据配方器 × 证书中间件 × 混合调速器（四层架构 v8）

> 承接第 42 轮产物 v19。本轮**增量插入** IP-57/58/59，并升级 IP-54/55/56/51/52/53/49/50/45/47；不推倒任何既有层级。核心是把 v19 的「仿真→检索→边缘→仿真」飞轮，补上**数据成分控制**（数据配比）与**证书运行时载体**（中间件）两根调速轴，使飞轮具备预算自适应与逐跳可追责能力。

### IP-57 CDM：混合定律拟合、配比优化与主动采集
```
def fit_mixing_law(recipe_trials):
    # recipe_trials: [(m_k, delta_holdout_k, tau_k, cost_k)]
    # 单调约束：delta 对 w_i 递减，tau 对 w_i 递增
    return MonotoneGP(log_x=[log(m) for m,_ in trials],
                      y_delta=[d for _,d,_,_ in trials],
                      y_tau=[t for _,_,t,_ in trials],
                      constraints='delta↓,tau↑')

def estimate_delta_IS(m, n, p_true, ess_min=200):
    xs, ws = [], []
    for _ in range(n):
        x = sample_mixture(m)              # q_m
        w = p_true(x) / mixture_pdf(m, x)  # 重要性权重
        xs.append(violation(x)); ws.append(w)
    ess = (sum(ws)**2) / max(1e-12, sum(w*w for w in ws))
    if ess < ess_min: return None, ess    # 估计作废
    return sum(w*v for w,v in zip(ws,xs))/n, ess

def optimize_recipe(surface, delta_max, B, m_ref, eps_mix):
    # 投影梯度解 min tau s.t. delta<=delta_max, cost<=B, KL(m||m_ref)<=eps_mix
    m = m_ref.copy()
    for _ in range(T):
        g = grad(surface.tau, m) + lambda_ * grad(relu(surface.delta(m)-delta_max), m)
        m = project_simplex(m - eta*g)
        m = project_kl_ball(m, m_ref, eps_mix)
        m = waterfill_cost(m, B)          # 成本注水
    return m, surface.marginal_returns(m) # 输出 per-source 边际收益

def active_acquire(m, budget, ledger):
    # 单位成本期望漏报下降最大者优先；反例源用稀有事件 IS 提议
    scores = {src: surface.marginal_delta(m, src) / cost[src] * confidence[src]
              for src in S}
    return argmax(scores), scores

def audit_recipe(m, delta_train, n_holdout):
    d_hold, ess = estimate_delta_IS(m, n_holdout, p_true)
    if d_hold is None: return 'INCONCLUSIVE'
    return 'PASS' if abs(d_hold-delta_train) <= 2*sigma(d_hold) else 'ROLLBACK'
```

### IP-58 CMW：证书胶囊、逐跳契约与 QoS 降档
```
# 胶囊定长布局（示例，字节）
# [0:8] h_cert | [8:16] key | [16:28] theta i16[6] | [28:36] t_issue,t_exp
# [36:44] prov_hash | [44] mode | [45:64] sig

def cmw_publish(msg, cert, mode):
    cap = pack_capsule(hash(cert), cert.valid_key(msg.state),
                       cert.theta, now(), cert.expiry,
                       prov_chain(cert), mode, sign=bus_key)
    return msg.with_attachment(cap)       # 零拷贝 CDR

def cmw_deliver(msg, hop, env):
    cap = msg.capsule
    checks = {
        'fresh':   cap.t_exp >= now(),
        'in_region': cap.key in hop.C_h.valid_region(msg.state, env),
        'contract': implies(hop.post, next_hop(hop).pre),
        'timing':  elapsed(msg) + hop.T_h <= hop.deadline,
        'integrity': verify(cap.sig, bus_pubkey) and cap.h_cert == hash(hop.C_h),
    }
    if all(checks.values()):
        ledger.log(now(), hop.id, msg.id, cap, 'PASS', env_ctx(env))
        return 'DELIVER', cap.mode
    # 失败定位到具体 hop，写账本供 IP-59 归因
    ledger.log(now(), hop.id, msg.id, cap, 'FAIL:'+first_false(checks), env_ctx(env))
    return 'DOWNGRADE', degrade(cap.mode)

def qos_to_mode(q, cert):
    # 可调度性：Σ C_h/T_h <= U_max 且 T_verify <= min deadline
    if cert.T_verify > min(q.deadlines): return 'SAFE'
    if q.slack < cert.T_verify + cert.T_hold: return 'SAFE'
    if q.reliability < r_min or q.liveliness_expired: return monotone_down(cert.mode)
    return cert.mode

def compose_hop_contracts(automaton):
    hops = []
    for e in automaton.E:
        hops.append(Hop(pre=e.src_invariant, post=e.dst_invariant,
                        C_h=e.certificate, T_h=e.wcet))
    for a, b in zip(hops, hops[1:]):
        assert implies(a.post, b.pre), "契约不精化，拒绝组合"
    return hops
```

### IP-59 MG：归因驱动的预算注水与稳定性护栏
```
def governor_step(ledger, surface, m_t, B_t):
    # 1. 账本切片归因：按 hop / 环境 / 配方桶估计反事实效应
    ate, sigma = {}, {}
    for src in S:
        ate[src], sigma[src] = counterfactual_ate(ledger, src)
    # 2. 归因不可信 → 冻结该源（防自指放大）
    trust = {src: sigma[src] <= SIGMA_MAX for src in S}
    # 3. 用实机账本校正 H-Mix 的 delta 项（贝叶斯更新）
    surface.update_delta(ledger_slices=slice_by(ledger, ['hop','env','recipe']))
    # 4. 预算注水：边际收益/成本高者多分，保留实机标定最小配额
    alloc = waterfill({src: max(0, ate[src]) * trust[src] / cost[src] for src in S},
                      B_t, floor={'S_real': B_real_min})
    # 5. 信任域内小步重配 + 迟滞
    m_next = optimize_recipe(surface, delta_max, B_t, m_t, eps_mix)
    if not all(trust.values()): m_next = blend(m_t, m_next, alpha=0.2)
    V = surface.tau(m_next) + lambda_ * max(0, surface.delta(m_next)-delta_max)
    return m_next, alloc, {'V': V, 'frozen': [s for s in S if not trust[s]],
                           'why': explain(ate, sigma, alloc)}
```

## 6. 本轮最大风险

**一句话**：把证书质量绑在「数据归因」与「时序耦合」两根新支柱上——若中间件账本对失败的归因存在系统性偏差（例如把延迟引起的失败错记到感知数据头上），配比优化会放大错误数据源，形成「越优化越自信、越自信越漏报」的自指闭环；而胶囊注入拉长消息路径，本身又可能成为新的 deadline 违约源，使安全开销反向制造不安全。这是本轮方案的最大风险，必须以 E88 的留出集双通道审计与 E89 的时延预算红线双重设防。
