# 第 10 轮（新灵感循环第 2 轮；本轮灵感：「行为树」×「应用落地」）
> **基线**：第 9 轮 MetricVoiceGauge-ACMD（定义 532–539；引理 82–86；实验 E551–E570）。
> 本轮纪律：**任务级反应式退化 + 落地证据门控**。v9 已把"模块失效"代数化，却把"任务失败"留给了隐式策略；v9 已有 20 个仿真实验，却没有任何"可交付部署"的判据。本轮用行为树治理前者、用部署就绪栅格治理后者；核心红线：**BT 的任何回退都必须是 v9 退化格中的一次向下移动（≼），且回退必须记账、可审计、可强制升级**——绝不允许"任务看起来成功"掩盖"系统已在陌生域降级运行"。

## 0. 直觉与动机

**灵感 1（行为树 → 退化策略的语法）**
直觉：v9 的五级退化链本质是一个**手写的、线性的、全局的** fallback 序列；真实任务需要的是**局部的、组合的、上下文相关**的 fallback：抓取失败该换抓取姿态，而不是关掉整个感知；导航被堵该局部重规划，而不是全系统降级。行为树（BT）的 Sequence/Fallback/Parallel/Decorator 恰好是"尝试—失败—换路"的语法，而且它的控制流是显式、可检查、可编辑的。核心创新：**契约化行为树（Contracted Behavior Tree, CBT）与 BT 编译器（BTC）**：每个叶节点携带 v9 契约 κ_v（前置/后置/不变式/时限/中立元/蒸馏资格），组合节点携带组合契约；编译期把 BT 展平成 v9 的 ContractMiddleware 调度表，运行期以 50Hz tick + v9 动作块执行。于是"任务级 fallback"与"模块级中立元"统一到同一套退化代数里。

**灵感 2（应用落地 → 把"能跑"变成"敢交付"）**
直觉：v9 的 E551–E570 全是受控仿真，证明的是"机制正确"，不是"现场可用"。应用落地的真正约束是：部署是分阶段的（离线回放→软件在环→硬件在环→影子模式→有人监督→自主）、每个阶段能解锁哪些行为必须由证据决定、失败必须能回滚。核心创新：**部署就绪栅格（Deployment Readiness Lattice, DRL）+ 现场证据账本（Field Evidence Ledger, FEL）**：每个 BT 节点/子树有一个"证据成熟度"，DRL 的每一级是一个可判定的门控谓词；门控只放行证据覆盖到的子树，且现场每条证据以哈希链追加、可审计、可 O(1) 回滚到 v9。

**灵感 1×2 的耦合洞见（BT 是退化策略的语法，落地是它的语义证据）**
直觉：BT 让"退化"从全局线性链变成局部可组合的树；但树越可组合，越容易**把退化藏进成功路径**——fallback 子树完成了任务，监控却看不到主路径已经失效。因此 BT 必须与一个**退化债记账器（Degradation Debt Accountant, DDA）** 绑定：每次 fallback/中立元注入都记一笔债，债超预算即强制升级（安全停驻或请求接管），而不是继续"成功地降级"。这把 v9 的"最需要安全时证书最不可靠"推进为"最需要证据时不许用成功掩盖降级"。

## 1. 研究问题（轮次升级版）

- **Q1（BT 组合可靠性）**：在什么叶契约与组合守卫条件下，整棵 CBT 的根契约可由叶契约**组合式**推出（而非枚举验证）？50Hz tick 与 v9 5Hz 动作块如何对齐，使"BT 认为 SUCCESS"与"动作块真正执行完"不产生时序空洞？
- **Q2（回退安全性与退化债）**：如何定义 BT fallback 的细化偏序，使任何回退都严格落在 v9 退化格内？退化债如何记账、如何设预算，才能在有限窗口内**必然**触发升级，从而杜绝"静默回退"？
- **Q3（落地门控的可靠性）**：DRL 门控谓词需要多少现场证据覆盖、在什么分布漂移假设下，才能把"通过第 l 级"转化为可辩护的现场失效上界？门控、回滚与操作员接管如何保证无优先级反转？

## 2. 设计原则（在 P10–P12 基础上新增 P13–P15）

**P13 契约化行为树律（Contracted Behavior Tree, CBT）**
任务逻辑一律写成 CBT：叶节点 = v9 动作块/条件检查，携带契约 κ_v=(pre_v, post_v, inv_v, D_v, Ŵ_v, v_v^⊥, φ_v^elig)；组合节点只允许 Sequence/Fallback/Parallel/Decorator 四种，且每个组合节点声明组合守卫。禁止在叶节点内写隐式 if-else fallback；所有 fallback 必须是显式 BT 边。

**P14 回退细化与退化债律（Refinement + Debt, RDL）**
每条 fallback 边 u→v 必须满足 T_v ≼ T_u（v 是 u 的安全细化/降级），由编译期检查器验证；运行期每次进入 ≺ 严格边记一笔退化债 d(t)，预算 D_max 内债不得为负，超预算强制升级（安全停驻/接管）。回退不是免费的：它必须被计数、被审计、被偿还。

**P15 落地证据门控律（Landing Gate, DRL）**
部署分 6 级（DRL-0..5）；第 l 级门控谓词 γ_l 只依赖 FEL 中可验证证据与 BT 可达节点集；未通过 γ_l 的子树在运行期被编译为 `v^⊥`（不执行），等价于 v9 对应退化级；回滚是 O(1) 的契约表切换，不重新编译。

## 3. 与基线的接口（如何退化）

- BTC 失效（编译失败/契约不一致）⇒ 直接运行 v9 的 ContractMiddleware 调度表，等价 v9；
- BT 运行器失效（tick 超时/栈损坏）⇒ 冻结当前子树，回退到 v9 单块执行器，等价 v9；
- RDL/DDA 失效 ⇒ 关闭回退细化检查与债务记账，BT 退化为"纯 fallback 解释器"，所有边等价 v9 显式中立元注入（审计降级）；
- DRL/FEL 失效 ⇒ 所有已部署节点按最高成熟度放行，等价"无落地门控"的 v9 现场版；
- v9 的 AC/MW/ID 任一失效 ⇒ 按 v9 定义 532–539 退化到 v8；
- 全失效 ⇒ 逐级退回 v8 → v7 → v6。

## 4. 预期贡献

1. **契约化行为树**：把任务级 fallback 从隐式代码变成可编译、可组合、可形式检查的契约树，并与 v9 中立元退化链统一；
2. **回退细化 + 退化债**：给出"回退必须向下、回退必须记账"的代数约束与有限窗口强制升级定理，堵住静默回退；
3. **部署就绪栅格 + 现场证据账本**：把"应用落地"从叙事变成 6 级可判定门控 + 可审计证据链 + O(1) 回滚；
4. **BT×AC×MW×ID 的闭环**：E571–E590 覆盖编译等价、组合可靠性、反应延迟、退化债、落地门控、分布漂移、接管、长跑、真实任务与安全案例生成。

## 5. 本轮最大风险

**一句话**：行为树的 fallback 会把"可检测的模块退化"包装成"任务仍然成功"——主路径已失效、回退子树在陌生域里勉强过关，而监控与 ID 归因只看到"成功"；若退化债的预算与升级阈值标定不当，系统就会在"看起来正常"的状态下长期运行于已验证包络之外，即**回退洗白（silent fallback）**，这是落地阶段最危险的失败模式。

**新增定义 540（契约化行为树 Contracted Behavior Tree）** T=(V,E,type,κ,ρ)，type(v) ∈ {Seq, Fallback, Par, Decorator, Action, Condition}。Action 叶执行 v9 动作块 ζ 的第 k 步；Condition 叶是只读谓词。组合语义：Seq 顺序执行直到 FAILURE；Fallback 依次尝试直到 SUCCESS；Par 并行且要求 m-of-n；Decorator 提供 Retry/Timeout/Inverter/ForceSuccess。禁止叶内隐式 fallback。

**新增定义 541（节点契约 NodeContract）** 每个 Action/Condition 叶声明 κ_v=(pre_v,post_v,inv_v,D_v,Ŵ_v,v_v^⊥,φ_v^elig)。post_v 用 v9 六层指标与任务谓词表达；inv_v 必须包含 v9 安全不变式（CVC、SpatialCert、RT-CVC、FaultCert）。组合节点 κ 由子节点与守卫按定义 543 导出。

**新增定义 542（tick 语义与块-树相位对齐）** BT tick 50Hz，Action 叶在 RUNNING 时绑定 v9 动作块 ζ；相位对齐条件：叶在块第 k 步返回 RUNNING，直到 k=K_eff 或 v9 中块守卫中止。若 BT 在块中途切换叶，必须先执行 ζ 的中止点 p*（v9 定义 534）再切换。故每次 RUNNING→SUCCESS/FAILURE 迁移只能发生在块边界或中止点。

**新增定义 543（契约组合规则）**
```
Seq:      post = post_n ∘ ... ∘ post_1,  pre_i 需被前驱 post 蕴含
Fallback: post = post_1 ∨ ... ∨ post_n,  inv = ∧ inv_i
Par:      post = ∧ post_i,                inv = ∧ inv_i
Decorator: 保持 inv，仅收紧 D/Ŵ
```
组合守卫 g 必须满足 pre_v ⟹ g。

**新增定义 544（安全细化偏序 ≼）** T' ≼ T 当且仅当：(i) inv(T') ⊇ inv(T)（不引入新的不安全状态）；(ii) 对任意环境输入，T' 的每条可执行轨迹都是 T 的某条轨迹的"能力弱化"（post 单调不增）；(iii) D(T') ≤ D(T) 且 Ŵ(T') ≤ Ŵ(T)（资源不增）。≼ 为偏序，且对 Fallback 的 join 保序。

**新增定义 545（退化格 Degradation Lattice）** L=({v10,v9,v8,v7,v6} ∪ 局部回退层, ≼, ⊔, ⊓)，其中 v10 ≽ v9 ≽ v8 ≽ v7 ≽ v6。BT 每条 fallback 边 u→v 要求 v ≼ u；⊔ 对应"取更强能力"，⊓ 对应"取更安全"。回退只能沿 ≼ 向下，禁止横向或向上跳变。

**新增定义 546（退化债 Degradation Debt）** 每次执行严格回退边（v ≺ u）记 w_e ≥ 0，中性元注入记 w_⊥；债务动力学：
```
d(t+1) = max(0, d(t) + Σ_{回退} w − r·Δt)
```
预算 D_max；若 d(t) ≥ D_max 或窗口 W 内回退频率 ρ_fb > f_max，则触发强制升级 E(t) ∈ {safe_stop, request_takeover, full_wake}。

**新增定义 547（部署就绪栅格 Deployment Readiness Lattice）** 6 级：DRL-0 离线回放、DRL-1 软件在环、DRL-2 硬件在环、DRL-3 影子模式、DRL-4 有人监督、DRL-5 自主。门控谓词：
```
γ_l(T) = [cov(T) ≥ c_l] ∧ [每叶至少一次成功/失败证据] ∧ [ODE 内无未解释回退] ∧ [回滚演练通过]
```
只有 γ_l 为真的子树可解锁第 l 级行为。

**新增定义 548（现场证据账本 Field Evidence Ledger）** 追加式哈希链，记录 (时间, 节点 id, 运行包络标签, 结果, 回退边, 退化债快照, 证据摘要)。cov(T) 为 T 中在 ODE 内至少被观察到一次成功与一次失败模式的叶比例；账本支持 O(log n) 存在性证明与 O(1) 回滚指针。

**新增定义 549（运行包络 ODE 与操作员接管契约）** ODE = ∧_{v∈V} pre_v 与场景假设（光照、地面摩擦、障碍密度）之合取；ALI 不变式：只要 ODE 成立且 γ_l 通过，系统不进入未验证的退化路径。Takeover 为最高优先级 Decorator，接管延迟 H ≤ 1 tick + 一个中止点；接管期间 BT 冻结、v9 安全停驻保持。

# IP-357 BehaviorTreeCompiler：契约化行为树编译器
@dataclass
class NodeContract:
    pre: Predicate; post: Predicate; inv: Predicate
    deadline_ms: float; wcet_ms: float
    neutral: object; distill_eligible: bool

class BehaviorTreeCompiler:
    def compile(self, T) -> Schedule:
        self._check_contracts(T)              # 定义 543 组合规则
        self._check_refinement(T)             # 每条 fallback 边 v ≼ u（定义 544/545）
        schedule = Schedule()
        for v in self._leaves(T):
            schedule.add(Contract(
                name=v.id, deadline_ms=v.k.deadline_ms,
                wcet_ms=v.k.wcet_ms, fail_value=v.k.neutral,
                bt_node=v.id, refines=v.refines))
        return schedule                        # 直接喂给 v9 ContractMiddleware

    def _check_refinement(self, T):
        for (u, v) in fallback_edges(T):
            if not refines(v.contract, u.contract):   # 定义 544
                raise UnsafeFallback(f"{u.id}->{v.id} 不是安全细化")
```

# IP-358 DegradationDebtAccountant：退化债记账（定义 546）
class DegradationDebtAccountant:
    def __init__(self, D_max=1.0, r=0.01, f_max=0.2, W=500):
        self.d, self.D_max, self.r = 0.0, D_max, r
        self.f_max, self.W = f_max, W
        self.fb_window = deque(maxlen=W)

    def on_fallback(self, edge, neutral=False):
        w = edge.neutral_weight if neutral else edge.weight
        self.d = max(0.0, self.d + w)
        self.fb_window.append(1)
        if self.d >= self.D_max or self._freq() > self.f_max:
            return self.escalate()             # safe_stop / takeover / full_wake
        return None

    def on_healthy(self, dt):
        self.d = max(0.0, self.d - self.r * dt)
        self.fb_window.append(0)

    def _freq(self):
        return sum(self.fb_window) / max(1, len(self.fb_window))
```

## 4. 推导

**引理 87（BT 契约组合可靠性）** 若每个叶节点满足 κ_v，每个组合节点满足定义 543 的守卫蕴含关系，则根节点满足 κ_root。证明：对树结构归纳。Seq 由前驱 post 蕴含后继 pre；Fallback 由各分支 post 的并集覆盖根 post，且 inv 取交故更安全；Par 与 Decorator 同理。∎

**引理 88（回退细化安全性与退化格封闭）** 若所有 fallback 边满足 v ≼ u，则任一 BT 执行轨迹的每一步都在 v9 退化格 L 内；因此 v9 引理 82–86（块证书、中立元等价、蒸馏安全、防抖、EDF）在 BT 的每个状态上继续成立。证明：由 ≼ 的传递性与定义 545 的向下封闭；回退只减少能力与资源、不新增不安全状态。∎

**引理 89（BT 编译 ≡ v9 中间件）** 对 v9 的退化树 T_v9（五级链展开为退化 BT），`compile(T_v9)` 产出的调度表与 v9 手写 ContractMiddleware 逐位等价；未通过细化检查的树在编译期被拒绝，不进入运行期。证明：编译仅把叶节点重排为 EDF 并保留 κ 的中立元字段；回退边展开与 v9 显式分支一一对应。∎

**引理 90（反应延迟上界）** 设 BT 深度 h、tick 周期 Δ=20ms、动作块长 K_eff；若叶在 RUNNING 时绑定块且只在中止点/块边界切换，则从任一叶不变式被违反到进入安全状态的时间 ≤ h·Δ + Δ_stop；若违反发生在当前活动叶，则 ≤ Δ_guard + Δ_stop，其中 Δ_guard ≤ 1 tick，Δ_stop 为定义 534 的停车时间。证明：tick 逐层展开，每层至多一个 Δ；中块守卫每 tick 检查证书与停车不变式，故最坏不超过深度与守卫之和。∎

**引理 91（退化债有限窗口强制升级 / 无静默回退）** 设每次严格回退记 w ≥ w_min > r·W/ (f_max·W) = r/f_max，则任何长度 W 的窗口内回退次数 > f_max·W 时债务净增 > 0；由 D_max 有限，系统必在 ≤ ⌈D_max/(w_min·f_max − r)⌉ 个窗口内达到 D_max 或 ρ_fb 超阈，从而触发升级 E(t)。因此"持续成功但持续回退"的静默降级状态最多维持有限个窗口。证明：债务单调累加、偿还线性，净增率为正；计数界直接给出有限上界。∎

**引理 92（落地门控的覆盖-失效界）** 在分布稳定假设（现场输入落在 FEL 经验分布的 ε-邻域内）下，若 γ_l 通过（cov(T) ≥ c_l 且每叶至少一次成功/失败观测），则第 l 级部署的未验证回退概率 ≤ (1−c_l) + ε·Λ，其中 Λ 为 BT 对输入变化的敏感度常数。证明：未覆盖节点即未验证节点，其触发概率被 1−cov 界定；分布漂移项由 ε 与树的局部敏感性界定。∎

**引理 93（接管无优先级反转）** Takeover 为最高优先级 Decorator，编译期将其 deadline 设为 0 并放入独立抢占槽；接管延迟 H ≤ 1 tick + 一个中止点，接管期间 v9 安全停驻不被任何低优先级叶阻塞。证明：EDF 静态校验（v9 引理 86）加上抢占槽严格优先级；v9 停车不变式保证阻塞有界。∎

## 8. 本轮最大风险

**一句话**：行为树的 fallback 会把"可检测的模块退化"包装成"任务仍然成功"——主路径已失效、回退子树在陌生域里勉强过关，而监控与 ID 归因只看到"成功"；若退化债的预算与升级阈值标定不当，系统就会在"看起来正常"的状态下长期运行于已验证包络之外，即**回退洗白（silent fallback）**，这是落地阶段最危险的失败模式。
