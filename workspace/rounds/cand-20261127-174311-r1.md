## 1. 直觉与动机（两个灵感的碰撞 + 与既有清单的交汇）

**灵感 1（竞品分析 → 这不是黑箱比赛，隔壁已经把同款桌面任务的真机天花板量出来了）**
直觉：UniBot 榜单「即将发布」让人误以为没有外部参照。但竞品分析发现两个几乎同构的公开真机基准：RoboChallenge Table30（30 桌面任务、成功率+步骤分、每任务 100 分）与 RoboColosseum（含 **Unitree G1** 本体）。它们给出的不是「别人分数多少」，而是三条可操作先验：
(a) **天花板定位**——最易的 Table30 榜首 ~64%，更难的 V2 榜首 ~31%，G1 真机 ~0% 完成、13–23% 进度；用户上下文「榜首 <30%」完全落在这条曲线上，说明瓶颈是**普适的**，不是我们队伍独有；
(b) **排序不可迁移**——Kendall W=0.24，别体/别基准赢的配方未必在 G1/UniBot 赢，**外部结果只能做失败模式诊断，不能做排名背书**；
(c) **计分结构同构**——Table30 与 UniBot 都是「每任务 100、成功率+步骤分」，且 Table30 明示**每次重试扣 0.5**。
核心反直觉点：**竞品分析最大的产出不是「抄谁」，而是「拿到一个可复现的代理计分器 + 一份别处已验证的失败模式清单」，把稀缺真机预算花在真正的瓶颈上。**

**灵感 2（桌面操作 → 32 个任务本质是「桌面结构约束下的长程组合」，不是 32 个独立分类）**
直觉：桌面（tabletop）是机器人学里结构最强的场景之一：桌平面、支撑关系（在桌上/叠放/在容器内）、重力、可达域、目标区域。而 VLA-Arena 明确指出**长程技能组合是普适瓶颈**，Table30 V2 也在加长程与双手同时。于是「桌面操作」给了一个免费结构先验：把每个任务表示成**支撑关系场景图 + 官方得分点子目标序列**，让单模型在子目标条件下执行，而不是一口气端到端硬扛长程。核心反直觉点：**长程失败往往不是「不会做」，而是「不知道现在该做哪一步」——桌面结构能把「隐式长程规划」降级为「显式子目标跟随」。**

**两者统一**：竞品分析回答「往哪投、用什么代理计分、别信什么」，桌面操作回答「用什么结构先验去补长程短板」。与前序清单的交汇是：I2（数据）仍是底座，但增量收益要靠 I11 定位瓶颈、靠 I10 释放结构先验；I1/I5/I8/I9 都获得外部证据支撑的微调。

### 1.1 严谨定义（先直觉后形式化）

**定义 1（桌面支撑关系场景图）**：$G=(O,E)$。节点 $o\in O$ 为物体，属性 $a(o)=(\text{类别},\ \text{6DoF 位姿},\ \text{抓取可供性},\ \text{是否可形变})$；边 $e\in E$ 为关系，取值于 $\{\text{on},\ \text{inside},\ \text{stacked-on},\ \text{held},\ \text{left-of},\ \text{front-of}\}$。$G$ 由多视角 RGB（+可选深度/桌平面单应）在 $reset$ 与每个 chunk 边界估计，**推理期不引入独立学习大模型**（规则/几何为主，或作为辅助头并入同一 action-expert）。

**定义 2（得分点子目标序列）**：官方每任务得分点（F17）给出里程碑集 $\{m_1,\dots,m_K\}$；映射为可执行子目标序列 $\pi_g=[g_1,\dots,g_K]$，$g_k=(\text{目标物体},\ \text{动作原语},\ \text{目标区域/关系})$。子目标与得分点一一对齐，使「完成子目标」≈「拿到步骤分」。

**定义 3（子目标条件策略）**：$\pi_\theta(a\mid o_t,l,g_k)$，其中 $l$ 为 episode 指令、$g_k$ 为当前子目标。对照基线 $\pi_\theta(a\mid o_t,l)$。增益定义为 $\Delta\text{score}=\mathbb{E}[\text{stepscore}(\pi_\theta(\cdot\mid g))]-\mathbb{E}[\text{stepscore}(\pi_\theta)]$。

**定义 4（外部同构代理计分器）**：对公开基准 $b\in\{\text{Table30},\text{Table30-V2},\text{LIBERO-Long},\text{CALVIN},\text{RoboColosseum-G1}\}$，按 UniBot 同构公式 $\text{TaskScore}=100-\sum_{\text{retry}}0.5-\text{未达分}$、$\text{Total}=\frac1{32}\sum\text{TaskScore}$ 估计代理分 $\hat S_b$；其用途分级见 PR6。

## 2. 对前序痛点的增量修订

- P1（弱任务支配平均分）补充：Table30 证实弱任务（长程/软体/精确插入）普遍低分，且**重试扣分**——弱任务的「一次做对」比「多次试错」更值钱。
- P2（泛化缺口）补充：外部证据显示长程/推断退化是普适的（F24），泛化不只是外观轴，还有**组合轴**（子目标顺序/数量）。

## 4. 设计原则（新增 PR6/PR7，其余保留）

- **PR6 竞品证据分级**：外部结果分四级——①天花板参照、②失败模式诊断、③配方筛选、④排名背书。①②③可用；**④禁用**（W=0.24，F22）。任何「因为 X 在别处第一所以照搬」的论证一律降级。
- **PR7 桌面结构先验律**：凡任务可用支撑关系/目标区域显式描述，优先用显式结构把长程降级为子目标；结构先验必须可退化为「无」（不伤标称场景）。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I1 v3 考纲校准五轴增广引擎（物理一致版）★★★★★
- **动机**：（v1.1 保留）计分的真机评测每次在 5 轴上偏离训练分布，泛化缺口是全局乘性损失。
- **本轮深化（桌面操作）**：把 v2 的「按考纲随机化」升级为**物理一致增广**——位置轴用**桌平面单应**做落地一致的平移/旋转（物体始终落在支撑面上），干扰物轴用**支撑感知插入**（新物体按 on/inside 关系放到合法位置），叠放轴遵守**重力一致**（不允许悬浮/穿插）。直接回应上轮标记的「位置重拼接物理不可行」风险。
- **与现有方案差异**：直接 SFT 用标称数据；盲目增广用无校准、非物理的随机 warp。本点让增广样本**在桌面上物理可达**，减少「教坏动作」。
- **技术可行性**：高。桌平面单应 + 支撑关系可由单目/深度估计；考纲卡半自动（LLM 解析 wiki + 人工校对，~10min×32）。
- **所需资源**：分割/inpainting 1×24GB GPU（官方单卡微调，F11）；磁盘同 v1.1。
- **落地步骤**：①32 张考纲卡；②桌平面单应 + 支撑关系工具；③背景/干扰物两轴放量；④外观/位置 L0 消融；⑤剂量-响应定档。
- **风险**：考纲卡与真实评测偏差（缓解：单任务通道抽测 + 官方示例截图对齐）；物理一致增广仍可能遗漏接触动力学（缓解：I5 合成接触段补足）。

### I2 v3 数据引擎 3.0：孪生迁移 + G1 跨任务示教 + 策展式多样性 ★★★★★
- **动机**：单模型平均分被最弱任务支配（P1）；示教语料与质量双重浪费（P8）；外部证据显示**数据/配方比基座更决定真机分数**（Table30：DM0 62% > π0.5 42.7%），但**盲目多样性会伤未见物体泛化**（F24）。
- **本轮深化（竞品分析 + 桌面操作）**：
  1. **保留 v1.1 三件事**：110 语料孪生入训、官方 loader 加权 patch、示教质量加权。
  2. **新增 G1 跨任务示教**：RoboColosseum 公开的 **Unitree G1** fine-tune 示教（carry box / fold towel / load clothes / plate into rack / hang keys，Pico VR 遥操作，Apache-2.0）与考题**同体同夹爪**——用于补**低层动力学/本体先验**（不是任务语义），低权重入训，防止跨任务语义污染。
  3. **策展式多样性**：按 F24，低层数据不是越多越好——按**任务家族均衡**采样，并在 L0 中显式留出「未见物体」轴，只有不伤该轴的多样性才放量。
- **与现有方案差异**：均匀混训把容量浪费在已会任务/低质示教；无脑加多样性会伤 OOD。本点诊断先行、家族均衡、同体先验受控。
- **技术可行性**：高（LoRA/frozen-VLM 单卡起步，F11）。

```python
def build_scene_graph(obs, table_plane):
    objs = open_vocab_detect(obs.images)                 # 节点 O
    for o in objs:
        o.pose = backproject(o, table_plane)             # 桌平面约束下的位姿
    E = []
    for a, b in pairs(objs):
        if   on_top(a, b, table_plane): E.append((a, "on", b))
        elif inside(a, b):             E.append((a, "inside", b))
        elif held_by(a, b):            E.append((a, "held", b))
    return SceneGraph(objs, E)

def scoring_subgoals(task_id, G, syllabus):              # syllabus = 官方得分点(F17)
    K = syllabus[task_id].milestones                     # 里程碑集合
    return [match_milestone(m, G) for m in K]            # 与得分点一一对齐

class SubgoalPolicy:                                     # 仍是同一个 PolicyService / 单模型
    def reset(self, obs):
        self.G   = build_scene_graph(obs, self.table_plane)
        self.sub = scoring_subgoals(self.task_id, self.G, SYLLABUS)
        self.k   = 0
    def get_action(self, obs):
        if self._chunk_boundary(obs) and reached(self.G, self.sub[self.k], obs):
            self.k += 1                                  # 只在 chunk 边界推进子目标
        prompt = self.lang + " | subgoal: " + self.sub[self.k].text
        return self.vla(prompt=prompt, obs=obs)          # 子目标作软条件，非新模型
```

### 1.4 重试扣分感知的「放弃 vs 重试」门（I5 v3）

```python
def should_retry(p_success, marginal_score, retry_cost=0.5, cont_loss=0.0):
    # Table30/UniBot：每次重试扣 0.5；只有期望净增益为正才重试
    return p_success * marginal_score - retry_cost - (1 - p_success) * cont_loss > 0
```
