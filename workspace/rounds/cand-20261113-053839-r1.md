# 第 3 轮迭代（灵感循环 v3：「智能体」×「工具调用」）—— 把策略从「反射函数」重构成「有回合预算、要跟破坏者抢回合」的智能体

> **本轮是「换设计单位」，不是推倒 v2。** v2 把比赛看成"远程策略 `f(obs)→action` + 计分步骤 + Gazebo 造数据"。这一轮把单位从"函数"换成"智能体的一个回合（turn）"。读通接口后会发现一个被 v2 忽略的硬事实：评测端每次 `get_action` 只给你**一次观测**，你必须返回一个**形状恰为 `(T_a,…)` 的动作块**，然后评测端把整块**开环执行完**才再次调用你。也就是说，在你"闭眼"的 `T_a` 个控制步里，世界（包括那个人为干扰者）可以自由演化。把这两个灵感词读通，得到三个反直觉结论：
>
> 1. **`T_a` 在握手时就冻结了**（README §3：每次返回形状必须恰为 `(T_a,…)`）。所以 v2 的 UIP-13「按阶段动态换块长」在协议上不成立——反应性是**全局一次性选择**，不是逐段可调旋钮。若想"接触密集时才高频看"，协议不允许。
> 2. 真正的实时性因此不在"块长调度"，而在**盲执行段内的动作必须自稳**，以及**下一个回合立刻做最值钱的核验**。
> 3. 那个人为干扰者不是环境噪声，而是**第二个智能体**：它在你两次观测之间免费出手，且按 `human_*` 文本专挑你刚做完的步骤反向撤回。评测因此是一个**回合制对抗博弈**，而不是单智能体 POMDP。
>
> 一句话：**v2 在"动作"层面找创新；v3 在"回合与工具"层面找创新。** 参赛策略应当是一个**工具调用型智能体**：把 32 个任务编译成"技能程序"，每个回合只调用少量**有类型的内部工具**（核验/规划/执行/恢复/探测/弃权），并用 `human_*` 文本预编译出**对手模型**来决定"这一回合该核验哪个子目标"。所有工具要么是确定性代码、要么是同一骨干上的头——因此仍然是**单模型**。

**必须显式标注的两条工作假设（本轮全部推理都挂在它们上，且都可证伪）：**
- **A1**：正式评测**包含** `human_*` 人为干扰（规则文本有，但评测是否执行未核实）。
- **A2**：步骤分**可被撤回**（即先达成、后被破坏会丢分），而不是"首次达成即锁定"。若 A2 不成立，本轮一半的恢复投资应转向"尽早拿高分末步"。

## 1. 直觉解释（先讲人话）

把评测想成一次**野外任务**，你只能在**固定的几个时刻**用无线电汇报一次，然后必须把接下来 `T_a` 步的动作**一次性写死**交给执行器；执行器跑完这 `T_a` 步后，无线电才再次接通。而你的对手——那个"人为干扰者"——恰好在你无线电关闭的这段时间里行动：你刚拧开瓶盖，它给你拧回去；你刚拉上拉链，它给你拉开；你刚叠好第二个碗，它给你拿下来。

于是你真正能做的只有三件事：

1. **在这一次汇报里，把接下来 `T_a` 步写成"即使被干扰也不会彻底毁掉"的动作**（自稳、留后路、可续接）；
2. **在下一次汇报时，优先问"最可能被撤回、且丢了最疼的那一步还在不在"**，而不是只顾往前冲；
3. **把任务的评分表当成一张"程序"来执行**：每个评分点是一个子目标，每个子目标对应一个可调用的技能工具；程序里预先写好"如果这一步被撤回，走哪条恢复分支"。

这就是"智能体"和"工具调用"在这个赛题里的真实含义：

- **智能体** = 一个**每回合只有一次观测、结果延迟 `T_a` 步返回**的异步决策者；它必须维护一个跨回合的"进度账本"（belief ledger），而不是把当前帧直接映射成动作。
- **工具调用** = 它不直接手搓每个关节，而是调用一组**有类型、有前置/后置条件、有代价**的内部工具：`Verify`（核验子目标）、`Plan`（选下一个技能）、`Execute`（唯一的**学习型**工具，产出动作块）、`Recover`（恢复）、`Probe`（用一小段安全动作换取信息）、`Abstain`（不确定时先不推进）。**关键合规点**：除 `Execute` 外，其余工具都是**确定性代码**，不是第二个模型；所以"工具调用"不等于"多模型"。

一个具体例子（T19 拉链）：规则里写了"拉上后再拉开"。普通策略拉上就继续下一个动作；工具型智能体则在拉上后的**下一个回合**立刻 `Verify(latch_closed)`，并把"拉链头"留在夹爪里（让对手没有机会拉开），一旦核验为 `regressed` 就直接 `Recover(zip)`。它不是"更聪明"，而是**把规则里的对手动作写进了程序的控制流**。

## 2. 严谨定义（再把话说死）

### 2.1 回合制协议（Turn Protocol）

设控制周期为 `Δt`，一个 episode 的控制步数上限为 `H`。策略在握手时选定固定块长 `T_a ∈ ℕ⁺`，于是 episode 被切成

```
N = ⌈H / T_a⌉   个回合（turn）
```

第 `n` 个回合：评测端给出观测 `o_n = O(s_{t_n})`，其中 `t_n = n·T_a`；策略返回动作块

```
A_n = (a_{n,1}, …, a_{n,T_a}),   a_{n,i} ∈ 𝒜
```

评测端**开环**执行 `A_n`（其间不再观测、不再调用策略），得到 `s_{t_n+T_a}`，然后进入下一回合。策略对 `A_n` 之后、下一次观测之前的世界**无信息、无控制权**。

> **定义 1（观测-行动滞后）**：记 `Δ_obs = T_a`（控制步）。它不是网络延迟，而是**协议强制的信息滞后**；网络/推理延迟只影响墙钟时间与可信度，不改控制步滞后。

### 2.2 对抗性插队（Adversarial Interleaving）

把人为干扰者建模为第二个行动者，动作 `u ∈ 𝒰`（反向关节运动、拿走物体、移动道具、挪底座等）。它在 `(t_n, t_n + T_a)` 窗口内可执行任意脚本动作，且**可观测全部真实状态**。于是评测是一个**回合制随机博弈**：

```
s_{t+1} = f(s_t, a_t, u_t),   a_t 由策略在回合边界成块给出，u_t 由对手在窗口内给出
```

对手的策略 `σ_h(u | s, task)` 由 `info.json.generalization.human_*` 的文本**部分给定**（这是本轮的核心信息源）。

> **定义 2（威胁模型）**：对任务 `T`，把每条 `human_*` 文本编译为元组
> ```
> h = (target, op, trigger, timing, magnitude)
> op ∈ {reverse_articulation, remove_object, relocate_object, disturb_base, occlude}
> trigger ∈ {after(φ_j), during(φ_j), at(step k)}
> ```
> 所有 `h` 的集合 `ℋ_T` 称为该任务的**显式威胁模型**。它是"规则白送"的对手代码，而不是要学的隐变量。

### 2.3 有类型的工具（Typed Tool Contract）

> **定义 3**：工具 `τ = (name, pre, post, cost, learned)`，其中 `pre` 是可由代码判定的前置条件，`post` 是写入账本的后置声明，`cost` 是本回合计算预算（毫秒），`learned∈{0,1}` 表示是否由学习参数产生。规定：
> - **闭世界**：评测期不允许任何网络/外部模型调用；
> - **单骨干**：所有 `learned=1` 的工具必须共享同一条骨干（这里是 `Execute` 与 `Recover`，可以是同一策略的不同模式）；
> - **纯函数性**：非 `Execute` 工具只读 `(o_n, ledger)`，不得改变世界。

工具集（v3 基座）：

| 工具 | pre | post | learned | 作用 |
|---|---|---|---|---|
| `Verify(j)` | 有观测、有子目标谓词 | 更新 `belief_j` | 否 | 判断 `done/regressed/fail/ongoing/unknown` |
| `Plan(𝒫)` | 有技能程序、有账本 | 产出下一个工具调用 | 否 | 解释程序、选边 |
| `Execute(skill, args)` | 前置满足 | 动作块 `(T_a,…)` | **是** | 唯一直接驱动身体的工具 |
| `Recover(fault)` | `status∈{regressed,fail}` | 恢复子目标 | **是** | 重做/重抓/重插 |
| `Probe(j)` | `belief_j` 熵高且安全 | 降低熵 | 否/可复用 Execute | 用安全动作换信息 |
| `Abstain` | 置信不足 | 安全保持块 | 否 | 不推进、不恶化 |

### 2.4 技能程序（Skill Program）

> **定义 4**：任务 `T` 的程序 `𝒫_T = (V, E, Λ, ℋ_T)`：
> - `V` = 节点，类型 ∈ `{Skill, Verify, Branch, Recover, Probe}`；
> - `E` = 控制流边（顺序 / 成功 / 撤回 / 失败）；
> - `Λ: V_skill → Tool` 把技能节点绑到工具；
> - `ℋ_T` = 威胁模型，用于给节点挂 `on_undo` 处理边。
>
> 程序由任务的语言指令 + 计分点结构 + `human_*` **离线编译**得到；运行期只做解释，不做重规划，从而保证**低且稳定的回合延迟**（直接服务可信度）。

### 2.5 回合级目标与可信度约束

> **定义 5**：记子目标集合 `{φ_j}`，权重 `w_j`（来自 `scoring_points`），`p_j(n) = Pr(¬φ_j | o_{1:n})` 为当前"已丢"的信念。回合策略 `π` 的目标是
> ```
> max_π  E[ Σ_j w_j · 1[φ_j(s_H)] ]            （成功率+步骤分）
> s.t.    Var(ℓ_n) ≤ σ²,   Anom(A_n) ≤ ε,      （可信度：延迟波动 + 动作规律性）
>         mean(ℓ_n) ≤ L,                        （每回合墙钟预算）
>         #learned_backbones = 1                 （单模型合规）
> ```
> 其中 `ℓ_n` 是第 `n` 回合的响应延迟，`Anom` 是动作统计异常度。**注意这是"带约束"的优化：更"聪明"的智能体如果更抖、更慢、更怪，反而会掉可信度。**

### 2.6 核验优先级（本轮的核心可计算量）

一个回合的算力只够核验 `m` 个子目标。设子目标依赖图 `G`，`desc(j)` 为 `j` 的后继。定义

```
V_j(n) = p_j(n) · [ w_j + Σ_{k∈desc(j)} κ_{j,k} · w_k ] · ρ_j
priority_j = V_j / cost_j
```

- `p_j(n)`：**被撤回的先验**，由威胁模型与"距上次核验的回合数"决定；
- 方括号：**基础价值**——不仅自己值钱，还是后续步骤的前提（`κ` 是依赖强度）；
- `ρ_j`：**可恢复性**（检测到后能否真的救回来；救不回的子目标不值得反复查）。
- 每回合取 `priority` 前 `m` 个核验。

> **命题（优先级的两个极端）**：若 `p_j` 只随"最近完成"升高（对手专挑刚完成的撤回），则优先级退化为 **LIFO（先查刚做完的）**；若 `p_j` 均匀而 `w_j` 集中在前置，则退化为 **Foundation-first（先查地基）**。真正的对手模型给出的是两者的**加权折中**，而不是任一极端——这正是"把 `human_*` 编译进控制流"比"通用撤回检测"更省核验预算的原因。

## 3. 上轮清单诊断（哪些被协议证伪、哪些升级）

- **证伪/须改写：UIP-13 ACS（自适应块长）**。v2 假设"可以每次返回 ≤K_MAX 步"，并据此"接触密集段用小 k"。但 README §3 要求动作数组形状**恰为 `(T_a,…)`**，且 `T_a` 在握手后不可变。因此"逐段换 k"是**协议违规**。正确做法是：**握手时一次性选 `T_a`**（用 §2.6 的回合预算权衡），运行期只能在**固定 `T_a` 内改变动作内容**（例如把块尾做成"安全保持/守卫运动"），不能改变观测频率。这是本轮最重要的纠错。
- **升级：UIP-01′（滚动验证-重做）→ 回合化、可调度化**。v2 只问"要不要核验"，v3 问"这一回合核验哪几个、按什么优先级、用多少预算"（§2.6）。
- **升级：UIP-09′（撤回检测）→ 威胁模型驱动**。从"通用检测 `regressed`"升级为"按 `human_*` 预编译对手、只在会被撤回的节点/时机布防"。
- **升级：UIP-15 CSG（可信度安全阀）→ 约束化**。从"加个延迟预算"升级为定义 5 里的**带约束优化**：智能体的"思考"必须被可信度约束住。
- **保留并归位**：UIP-02′（计分表）成为程序编译的输入；UIP-05（语言→可供性）服务未见物体；UIP-11（GSO）继续做离线步骤分裁判；UIP-12（DRF）为 `Recover` 工具造数据；UIP-14（MSGR）成为技能工具库；UIP-08′（多端口工程）保留。
- **合并掉**：UIP-13 的"投机预计算"并入 UIP-18（回合控制器）——但注意在固定 `T_a` 下，"投机"只能是"预生成下一块的候选、到时做一致性检查"，不能改变回合节奏。

## 4. 两个灵感词的解读

1. **智能体**：不是"给策略加个 LLM 壳"，而是承认它本来就是**异步、带记忆、带预算、要跟对手抢时间**的决策者。由此带来四件事：① 跨回合**信念账本**；② **异步工具结果**（结果延迟 `T_a`）；③ **对手也是智能体**（回合制对抗）；④ **行为要可被信任**（可信度约束）。第 4 点最容易被忽略：一个反复重试、块长抖动、动作跳变的"聪明智能体"，会先在可信度上翻车。
2. **工具调用**：不是"让机器人在线调外部 API"（那会违反单模型），而是**离线把任务编译成工具程序，在线只做轻量调度**。工具的"类型"体现在前置/后置条件与代价上；这让每回合的决策是**可审计的有限选择**，而不是黑箱大模型自由发挥。`get_action` 本身也可以读成"评测端对策略这个工具的一次调用"——所以策略要像好工具一样：**接口稳定、延迟稳定、结果规整**。

## 5. 瓶颈假设（v3 更新）

- **H1（最高杠杆，承接）**：人为干扰专撤回已完成进度，而公开数据零覆盖 ⇒ 谁先把 `human_*` 变成可执行的恢复程序，谁在这条轴上独占。
- **H5（本轮新增·协议层）**：`T_a` 固定 ⇒ **反应性是全局一次性选择**；小 `T_a` 换来更多核验回合，但抬高累计延迟/可信度风险；最优 `T_a` 由"对手活跃度 × 延迟代价"共同决定（见产物区推导）。
- **H6（本轮新增·信息层）**：由于回合内不可观测，**"盲执行段的动作自稳性"比"回合间的聪明规划"更决定成败**；接触密集任务尤其如此。
- **H7（本轮新增·对抗层）**：把干扰者当第二智能体（而非噪声）⇒ 存在**主动防御**动作：让已完成的进度"更难被撤回"（如把盖子留在夹爪里、把拉链头压住、把碗压到位），以及用 `Probe` 主动降低不确定性。
- **H8（本轮新增·可信度层）**：工具化/智能体化会提高延迟方差与动作异常率；**必须把"像机器人一样规律"作为硬约束**，否则成绩不可信。
- **H9（本轮新增·合规层）**：外部 VLM 工具在线调用 = 单模型风险；**闭世界工具集 + 单骨干 + 确定性工具**是可辩护的设计。

## 1. 旗舰深潜：UIP-16 · ATLAS（Agentic Tool Layer with Adversarial Skill-programs）

### 1.1 机制

ATLAS = **程序解释器 + 威胁模型 + 核验调度 + 工具层**，每回合严格四步：

1. **吸收观测**：用确定性 `Verify` 工具把最新 `o_n`（4 图 + 本体 + `delta` 堆叠）转成每个子目标的信念 `belief_j ∈ {done, ongoing, regressed, fail, unknown}` 与置信 `conf_j`；
2. **威胁加权调度**：本回合只核验 `priority` 最高的 `m` 个子目标（§2.6 公式），把算力花在"最可能被撤回且丢了最疼"的地方；
3. **解释程序**：用账本在技能程序 `𝒫_T` 上走一步，决定调用 `Recover / Probe / Abstain / Execute`；
4. **成块下发**：`Execute` 产出**恰 `T_a` 步**的动作块，块尾写"自稳/守卫"动作，使盲执行段内状态不崩。

### 1.2 与 v2 的差异（三点硬升级）

- **回合化**：v2 的验证是"每 k 步看一眼"的模糊描述；v3 明确"每回合一次观测、一次决策、一块执行"，并把它写成带预算的调度问题。
- **威胁化**：v2 的 `regressed` 是通用分支；v3 用 `human_*` 把"哪一步、什么时候、被怎么撤回"预先写进控制流，核验预算只花在真正的危险点上。
- **约束化**：v2 的可靠性是"加护栏"；v3 把延迟波动与动作规律性写成**硬约束**（定义 5），因为过度的重试/探测会先毁掉可信度。

### 1.3 为什么它是赛场最优的"低成本高杠杆"

- 只用接口内能力：`get_action` / `reset` / `metadata`，无外部网络、无额外机器人权限；
- 工具几乎全是代码：算力开销远小于再训一个模型，且延迟稳定（服务可信度）；
- 直接吃规则红利：`human_*` 是白送的对手代码，公开策略几乎没人把它编译进控制流；
- 与 v2 资产正交：GSO/DRF/MSGR 继续供离线数据与技能库，不需要推翻。

## 2. 形式化核心（可实现的定义）

### 2.1 回合协议与固定块长

```
N = ⌈H/T_a⌉,  t_n = n·T_a
o_n = O(s_{t_n})
A_n = π(o_1..o_n, ledger) ∈ 𝒜^{T_a}     # 形状必须恰为 (T_a, …)
s_{t_n+T_a} = f^{T_a}(s_{t_n}, A_n, u_{n,1..T_a})
```

**关键纠错**：v2 的 UIP-13 假设"每次可返回 ≤K_MAX 步"。README §3 明确每个动作数组形状为 `(T_a,…)`——返回更短是格式违规，且 `T_a` 握手后不可变。因此：

> **结论 18.1**：反应性不是"逐段旋钮"，而是**握手时的一次性全局选择**。运行期唯一能做的"变通"是在固定 `T_a` 内改变**动作内容**（块尾守卫/保持），而不是改变观测频率。

### 2.2 固定 `T_a` 的代价模型（给"该选多大块长"一个可算答案）

设单个回合的墙钟开销为 `λ`（网络 + 推理），对手在每步以概率 `q` 触发一次"会丢分的撤回"，被撤回后平均要过 `T_a/2` 步才被下一个回合发现，每步延迟发现造成的期望扣分为 `c`。则总期望损失近似

```
L(T_a) = q·H·c·(T_a/2)          # 撤回未被及时发现（随 T_a 线性变差）
       + (H/T_a)·λ              # 回合开销（随 T_a 变小）
       + μ·Var(ℓ)               # 可信度惩罚（小 T_a 通常回合更多、方差更敏感）
```

对连续近似求导并忽略最后一项：

```
dL/dT_a = q·H·c/2 − H·λ/T_a² = 0
⇒  T_a* = sqrt( 2λ / (q·c) )
```

**读法**：对手越活跃（`q` 大）、漏检越贵（`c` 大）→ 越该用**小** `T_a`；单回合网络/推理越贵（`λ` 大）→ 越该用**大** `T_a`。由于 `T_a` 必须一次性选定，最优策略是**为"对抗强度最高的任务族"统一取一个偏小的 `T_a`**，再用块内自稳去抵消其余任务的额外回合成本。示例（仅量级示意）：若 `λ≈80ms`、`q≈0.02/step`、`c≈2 分/step`，则 `T_a*≈sqrt(2·80/(0.02·2))≈63`——这说明**若网络很慢，宁可大块 + 强自稳**；若 `λ` 降到 5ms，则 `T_a*≈16`，小块的收益才显现。**结论：不要在没有实测 `λ` 前拍脑袋选小块。**

### 2.5 核验优先级（VPS）

```python
def priority(j, ledger, threat, G):
    p = threat.p_regress(j, ledger.age_turns(j), ledger.last_status(j))
    downstream = sum(w[k] * G.dep(j, k) for k in G.descendants(j))
    rho = ledger.recoverability(j)          # 能救回才有价值
    return p * (w[j] + downstream) * rho / cost[j]

def select_checks(ledger, m):
    return sorted(subgoals, key=lambda j: priority(j, ledger, threat, G), reverse=True)[:m]
```

**调度结论**：
- 若 `p` 仅随"最近完成"上升 → 退化为 **LIFO**；
- 若 `p` 均匀而 `w` 集中在前置 → 退化为 **Foundation-first**；
- `human_*` 编译出的 `p` 同时含"时间触发"和"目标"，因此得到**加权折中**：既查刚被点名的高危步，也查被撤回后会拖垮后续的地基步。

### 2.6 回合主循环（ATLAS）

```python
class ATLAS:
    def __init__(self, program, tools, verifier, scheduler, rtl, T_a, m):
        ...
    def reset(self):
        self.ledger = Ledger(program=self.P)     # 每端口/每 episode 独立
        self.hist = []
    def get_action(self, obs):
        self.hist.append(obs)
        # 1) 只读工具：更新信念
        self.ledger.update(self.tools["Verify"], obs)
        # 2) 威胁加权、预算受限的核验
        for j in self.scheduler.select_checks(self.ledger, m=self.m):
            st, conf = self.verify(j, obs)
            self.ledger.absorb(j, st, conf, threat=self.P.threat[j])
        # 3) 解释技能程序，选工具调用
        node = self.P.next(self.ledger)
        if node.kind == "Recover":
            call = ("Recover", node.j, self.rtl[node.fault])
        elif node.kind == "Probe":
            call = ("Probe",   node.j, self.probe[node.j])
        elif node.uncertain:
            call = ("Abstain", None,   self.safe_hold)
        else:
            call = ("Execute", node.skill, node.params)
        # 4) 成块下发：恰好 T_a 步；块尾守卫，保证盲执行段自稳
        chunk = self.dispatch(call)                         # shape (T_a, ...)
        assert chunk.shape[0] == self.T_a                   # 协议红线
        return self.pack(chunk)                             # 含 meta.token
```

## 3. 配套新件：PROBE / RTL / CAG / PSE / SCA

### UIP-22 · PROBE（主动信息获取）

- **问题**：回合内不可观测 + 无腕力/触觉 + 手常遮挡物体 ⇒ 视觉核验天然有盲区。
- **机制**：在"不确定但安全"时，返回一段**以获取信息为目标**的短程序（在固定 `T_a` 内）：轻抬 2cm 检验是否夹住、轻晃检验是否卡住、退开 5cm 露出被遮挡物体、绕到侧面看拉链状态。用期望信息增益 `IG(Probe) = H(belief_j) − E[H(belief_j | o')]` 选动作，并用安全约束排除会导致掉落的探测。
- **与 v2 差异**：v2 只会"继续执行或重试"；PROBE 是显式的**观测行动（active perception）**，把"看一眼"当成一个可调用的工具。
- **风险**：探测本身消耗步骤分/时间；只在 `p_j` 高且 `conf_j` 低时触发。

### UIP-23 · RTL（恢复工具库，升级 UIP-09′）

- **机制**：把 `human_*` 的每类撤回对应一个可调用恢复技能：`reopen` / `reinsert` / `restack` / `regrasp` / `retrieve` / `recap`。由 UIP-12 DRF 在 Gazebo 里生成 `(完成→撤回→恢复)` 三元组训练，并暴露为 `Recover(fault)` 工具。
- **新增**：除"恢复"外增加 **"防撤回"变体**（`keep_tab`、`keep_cap`、`seat_deep`），在 `Execute` 阶段就降低被撤回概率，减少后续回合消耗。
- **风险**：仿真干扰形态与真人不一致；用随机化时机/速度/轨迹 + 真机校准。

### UIP-24 · CAG（可信度约束治理器，升级 UIP-15）

- **机制**：把定义 5 的约束落到实现：① **回合延迟预算** `mean(ℓ)≤L`、`Var(ℓ)≤σ²`；② **重试/探测次数上限**；③ **动作形态平滑**（块间连续、避免突变/离群）；④ **决策抖动的抑制**（同一状态不因微小噪声反复切换工具）。
- **关键洞察**：智能体越"会思考"，越容易在可信度上翻车。CAG 是**给智能体踩刹车**的部件，不是可选项。
- **风险**：约束过紧会牺牲恢复能力 ⇒ 用 E206 画"分数-可信度"帕累托前沿再定阈值。

### UIP-25 · PSE（协议忠实仿真，离线）

- **机制**：离线实现一个"评测协议复刻器"：按 `T_a` 切回合、只在该边界给观测、整块开环执行、注入网络延迟分布、模拟 N 端口并发与状态隔离、注入 `human_*` 脚本干扰。**它仿真的是"协议 + 对手"，不是像素级物理**，因此成本极低、可大规模扫 `T_a`/调度参数。
- **与 GSO 的分工**：GSO 判"动作在物理上能不能达成计分步"；PSE 判"智能体在协议与对手下做得好不好"。二者互补，PSE 先行（便宜），GSO 校准（贵）。
- **风险**：协议忠实但物理不忠实，可能奖励"在仿真协议里聪明、在真机上无效"的策略 ⇒ 用 GSO + 真机锚点双重校准。

### UIP-26 · SCA（单模型合规审计）

- **机制**：给出可提交的合规证明：① 统计所有 `learned=1` 的工具共享同一骨干/权重；② 证明其余工具是确定性代码、无网络调用、无外部模型；③ 提供"单进程即可跑完一次握手+动作"的离线复现脚本。
- **为什么必要**：`Verify` 若用外部 VLM，很容易被判"非单模型"；SCA 把"工具调用≠多模型"讲清楚，降低评审歧义。
- **风险**：若评审口径极严（连确定性几何求解器也算"额外模块"），需退化为"全部用同一骨干的头"。

## 4. 实验设计 E201–E210（v3）

| 实验 | 对照 | 指标 | 目标/判据 |
|---|---|---|---|
| E201 | 固定 `T_a∈{1,2,4,8,16}` 全扫（PSE 上） | 成功率 / 步骤分 / 回合延迟 | 找到实测 `λ` 下的 `T_a*`；验证 §2.2 的 U 形 |
| E202 | 通用 `regressed` 检测 vs TIP 威胁程序 | 每核验次数的恢复分 `RSS`；误报率 | TIP 的 `RSS` 显著更高 |
| E203 | FIFO vs LIFO vs Foundation-first vs VPS | 恢复分 / 核验预算 | VPS 在不增预算下最优 |
| E204 | 被动核验 vs PROBE（遮挡任务 T12/T14/T29） | 误判率 / 恢复成功率 | PROBE 显著降低漏检 |
| E205 | PSE 排序 vs 真机/官方排序 | Spearman ρ | ρ 高 ⇒ PSE 可当便宜筛选器 |
| E206 | CAG 多阈值 | 分数 vs 延迟方差/异常率 | 画出帕累托前沿，定硬约束 |
| E207 | SPC 留一任务泛化 | 未见任务的程序可执行率 | 验证"计分点→程序"可迁移 |
| E208 | 脚本重试 vs RTL 恢复工具 | 恢复时延 / 二次破坏率 | RTL 更低时延、更少级联失败 |
| E209 | 单骨干审计 | learned 骨干数 / 外部调用数 | 恰为 1 / 0 |
| E210 | 端到端 ATLAS(16+17+18+19+20+21+22+23+24) | 综合分 + 可信度 | 相对 v2 基线显著提升且不触发可信度告警 |

## 5. 合规与风险

- **单模型**：唯一学习型工具是 `Execute/Recover`，共享同一骨干；`Verify/Plan/Probe/Abstain` 为确定性代码；无任何在线外部调用（UIP-26 审计）。
- **协议红线**：动作块形状必须恰为 `(T_a,…)`；`meta.token` 每步携带；`reset()` 必须真正清空每端口账本；N 端口状态隔离。
- **可信度**：延迟均值/方差、动作规律性是**被展示的**；CAG 必须把这当硬约束，而不是"跑完再看"。
- **假设风险**：A1/A2 未坐实；`human_*` 文本编译可能有歧义；`T_a` 若被真实网络延迟逼大，则反应性方案需整体回调（§2.2）。
- **仿真风险**：PSE 只忠实于协议，GSO 只忠实于结构；二者都不能替代真机锚点。

## 6. 资源与时间线（粗排）

- **第 0 周（最高优先）**：用一次官方/真机评测坐实 **A1、A2**，并实测单回合延迟 `λ` 与波动。若 A2 不成立，立即切换到"末步搏分 + 一次到位"变体。
- 第 1–2 周：TTL 工具层 + SPC 编译器（先覆盖 T19/T27/T14/T17/T12 五个撤回型任务）；PSE 协议复刻器上线。
- 第 3–4 周：TIP 威胁模型 + VPS 调度器 + PROBE；在 PSE 上扫 `T_a` 与 `m`，用 E201–E204 定参。
- 第 5–6 周：RTL 接 DRF 造数据；CAG 约束标定（E206）。
- 第 7–8 周：MSGR 技能库全 32 任务覆盖；多端口压测（UIP-08′）；SCA 审计。
- 第 9 周起：真机/GSO 校准锚点，复核 PSE 的排序相关性（E205），迭代。

## 7. 本轮最大风险 & 押注

**一句话**：整套框架的收益都挂在"步骤分可被撤回（A2）"这条未核实假设上；若评测在首次达成即锁定分数，则"回合级恢复"会瞬间失去意义，必须转身去优化"末步一次到位"——因此第 0 周的验证实验比任何架构都重要。

**→ 押注：UIP-19 SPC × UIP-20 TIP × UIP-21 VPS，装在 UIP-17 TTL 的闭世界工具层里，由 UIP-16 ATLAS 按回合调度，UIP-24 约束可信度、UIP-25 离线筛参。** 它把规则白送的 `human_*` 对手文本变成可执行控制流，用最少的回合做最值钱的核验，且完全落在选手 API 权限与单模型合规之内。
