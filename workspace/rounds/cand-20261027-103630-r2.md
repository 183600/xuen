# 第 2 轮 · SCORE-OS：操作系统不是比喻，长程不是时长，情感语音是负对照

> 检索/复核日期：**2026-10-27（UTC）**。研究线接续第 7 轮 PILOT，并吸收同日最新核对（含第 1 轮 SPARC 候选）的规则与数据修正；`research.md` 仍停在 PILOT，但本轮按用户指定记为「灵感循环第 2 轮」。赛事身份不变：宇树科技 **UniBot 世界挑战赛**（G1 + Dex1、32 项桌面任务、通才单模型、选手自部署 + 官方远程真机 API）。本轮三个灵感词是「机器人操作系统」「情感语音」「长程任务」。

先给结论：**操作系统要，但只能是策略侧运行时；情感语音不要，API 根本没有音频；长程任务要，但不是「时长长」，而是「进度可被现场人类撤销的非单调多阶段」。** 三者合成一个更锋利的主线：**把官方逐步评分表编译成运行时内核，用进度信念检测人为撤销，用接触技能内核保证终局操作，用成功优先的预算调度在 180s 内完成会话。** 方案名 **SCORE-OS**（Score-step Conditioned Operating Runtime for Embodied agents）。

## 0. 先纠五个偏差（否则这一轮会建立在沙子上）

### 0.1 榜单仍是占位，不能把「榜首 <30%」当真实天花板

页面当前渲染 8 个模型：`MolmoAct2 29.7/39.0`、`WALL-OSS-0.5 28.5/38.9`、`DreamZero 27.9/37.9`、`Spirit-v1.5 25.9/34.4`、`DM0 23.5/31.7`、`PI-0.5 22.8/30.6`、`GigaBrain-0 22.6/29.5`、`GR00T N1.5 20.5/28.1`（前者成功率，后者步骤分）。但：

- `leaderboard_data.json` 仍含 `"generated_from": "gen_leaderboard.py"`；
- 256 条详情视频仍是「测试视频占位」；
- 每任务 10 次运行，却出现 27.29% 这种两位小数成功率（正常应是 10% 的整数倍）；
- 这些数字与上一轮快照完全一致。

**结论：高度疑似占位/演示数据。** 不能从「榜首 29.7%」推出「30% 是上限」，也不能从任务级排名反推真实瓶颈。它只能当「任务看起来不简单」的弱先验。

**但另一件事是真实的**：这些模型的公开方法与其他真机基准成绩是真的。`DM0` 2.4B 在 RoboChallenge Table30 做到 62.0% specialist / 37.3% generalist；`Spirit-v1.5` 5B 在 Table30 拿过第一；`WALL-OSS` 4B、`MolmoAct2`、`DreamZero` 14B 都各有强项。也就是说：**不是「VLA 不会做真机」，而是「通用 VLA 没有为 UniBot 的 G1/Dex1 + 五轴扰动 + 接触精度 + 单模型运行时做适配」。** 如果榜单模型确实是零样本/少量微调，30% 更不是上限；`WLA-1.0-Base` 这种 G1/Dex1 原生底座 + 33k 官方数据微调，本身就可能是一个低垂果实。

### 0.2 排名是「成功率 > 步骤分 > 提交时间」，不是综合加权

官方手册明确：先按 32 任务**总平均成功率**排序；成功率相同按**总平均步骤分**；仍相同按**提交日期更早**。多次完整计分评测取**成功率最高的一次**；同分再取步骤分最高 [S1][S2]。

这推翻了 PILOT 里「成功率与步骤分综合排序」的写法，也改变了目标函数：

- **成功是 0/1 闸门；步骤分只在同成功率时破同分。**
- 不能为了多拿部分分而牺牲成功；不能把 `Σ w_i` 当主奖励。
- 终局步骤合计 39.8% 仍然是「成功闸门 + 最难的一步」，但不是「直接加 39.8 分」。
- 运行时调度目标应写成：`max P(all steps complete)`，`tie-break max E[Σ w_i 1_i]`；步骤权重用于**同分排序、验证优先级、失败诊断**，不是主目标。

### 0.3 人干扰是现场真人，不是固定脚本；官方备注是意图，不是逐帧剧本

这一点极其重要。官方说场景由测试人员**实时布置**，人为干扰是**真人现场操作**，不是固定脚本 [S1][S2]。任务 `info.json` 里的 `human_1_note` / `human_4_note` 是干扰的**场景说明/意图**，例如「叠了第二个之后拿下第二个」「拉上拉链之后拉开」「拧开盖子之后拧动回来」；它们不是评测时会逐帧照做的剧本。

所以：

- 备注仍然极有价值：它是**分布内的高价值扰动先验**，可以生成训练/恢复数据；
- 但不能把备注当精确 replay，否则会过拟合到「已知剧本」；
- `Progress Belief` 必须能检测**一般性的进度回退**，而不是只识别 32 条备注；
- 真人干扰意味着安全与等待策略也是运行时的一部分：人手进入工作区时应减速/停止，干扰结束后再恢复。

### 0.4 数据时间线要收回一句

当前数据事实：32 个数据集合计 **33,276 episodes / 18,282,246 frames / 169.28h**，约 1k episodes/task，30fps，四路 640×480 RGB，**没有 depth**；HangCup 1,043 episodes / 194,564 frames；collection `lastUpdated=2026-09-11`，单数据集 `lastModified=2026-10-14` [S5][S16][S17]。

但 `lastModified` 只是元数据，不能证明「最近两周扩容」。2026-08-18 社区帖说 HangCup 只有 44 条，当前 1,043 条，说明扩容确实发生，但**精确日期未证实**。PILOT 的「最近两周全量发布」应改为「8 月至 10 月之间完成扩容，具体日期未核实」。

### 0.5 单日一槽、不补测：调试槽不是免费 A/B

官方规则：每队**每日仅 1 个测试时段**，计分评测与不计分单任务调试都算；参赛方原因（网络、服务、超时、安全终止等）导致失败**不补测**；平台侧原因才另行安排 [S1][S2]。

这意味着：

- PILOT 的「每个大版本 1 个调试槽」过于乐观；真实可用槽位可能只有 **2–3 次**；
- 真机反馈必须留给**发布门**，不能当调参器；
- 离线/仿真/回放必须先过 gate，否则一次安全终止就浪费当天唯一时段；
- 安全不是「建议」，是直接保分/保资源。

## 1. 三个灵感词：一个要、一个不要、一个要但重新定义

### 1.1 机器人操作系统：要，但只能是 policy-side runtime

事实：G1 底层支持 ROS 2/DDS（`unitree_sdk2`、`unitree_ros2`），但评测只给 policy websocket API（`get_action` / `reset`），不能起 ROS node、不能读 DDS、不能控底层。**所以「机器人操作系统」不能理解成「在 G1 上装 ROS」；应理解成策略侧会话运行时（policy-side session runtime）。**

把 OS 概念逐项映射：

| OS 概念 | SCORE-OS 对应 |
|---|---|
| 进程 / 程序 | 一个任务会话 / 官方评分步骤图 |
| PC / 进程表 | 当前步骤 + 进度信念 + 撤销历史 |
| 系统调用 | 接触技能（insert / zip / unscrew / hang / pour / pick-out / stack / close / hold） |
| CPU 调度 | VLA / 技能 / 验证 / 回滚 / 停止 的选择 |
| 中断 | 人手移动物体、已完成步骤被撤销、安全风险 |
| checkpoint / restart | 最后一个已验证步骤；回滚后重做 |
| 地址空间隔离 | N 台机器人、N 个端口的 session 状态严格隔离 |
| watchdog | 180s 时间守卫 + 安全守卫 |
| 可观测性 | 步骤级日志、延迟、重试、失败原因 |

这不是比喻：它直接决定**每一步调用哪个动作源、花多少时间验证、何时回滚**，从而改变成功率。

与现有 robot OS / agent OS 工作的区别：

- `TypeGo`（SOSP 2026）做具身 agent 的 OS runtime、skill kernel、异步规划、抢占；
- `PhyAgentOS` 做 session-centered runtime、语义验证、记忆；
- `rosaOS` 做 OS-inspired、MCP + ROS；
- Nature MI 2026 的 ROS+LLM 框架做 behavior tree、skill learning、reflection。

它们共同证明「OS 抽象对长程具身任务有用」，但它们大多假设**能调工具/多模型/有机器人 OS 权限**，且不是为「官方评分表 + 单模型 + 部分分 + 对抗撤销」设计。我们的 runtime 是 **benchmark-native、single-checkpoint、policy-side**：没有 ROS，没有第二个模型，只有 WLA 一个 checkpoint + 确定性技能/调度。

与 PILOT 的 SSG 区别：SSG 只是状态机；SCORE-OS 是**Rubric Compiler + Progress Belief + Skill Kernel + Scheduler + Verifier/Rollback**，SSG 降为其中的编译器前端。

### 1.2 情感语音：不要，API 没有音频

事实：观测只有 4 路 RGB + 本体 + `observation.language` 单字符串；没有麦克风、没有音频、没有 prosody；指令 episode 内固定 [S6]。

`VLAS` / `AffectLoop` 等语音情感工作无法接入；强行加 speech encoder 是死通道，违反接口/单模型/延迟。**本轮明确剪枝情感语音**，不在模型、数据、评测里占预算。

唯一合法残留：把「情感/强调」降级为**文本负对照**——用中性 vs 强调/情绪化复述测语义不变性；如果成功率显著下降，说明语言 grounding 脆，但这不是主贡献，也不值得单开一节。若未来官方加音频，再开 hook。

顺带：真正与「人」有关的信号不是语音，而是**human 轴的动作撤销**（官方备注给了意图，现场真人执行），这才是本轮要抓的。

### 1.3 长程任务：要，但不是「时长长」，是「进度可被撤销的非单调多阶段」

事实：32 任务 2–5 个评分步骤；演示中位约 6–10s；上限 180s。按传统「长程 = 几分钟」定义，它不算长。

但 human 轴会**撤销已完成步骤**：

- T27：叠了第二个之后拿下第二个；
- T19：拉上拉链之后拉开；
- T14：拧开盖子之后拧动回来；
- T17：笔盒合上之后手动打开；
- T10：将插头拔起；
- T12：中途把锁拿走；
- T24：物品快到了然后放回传送带起点；
- T25：放了第一个马上放第二个、挪一下底座；
- T16：将叠完的毛巾翻开。

这使任务成为 **long-horizon in the small**：100–1000 个控制步、2–5 个语义步骤、**进度非单调**、部分分、成功 0/1。

现有长程工作提供 memory / verifier / rollback：

- `HELM`：结构化记忆 + 状态验证器 + 回滚，LIBERO-LONG 58.4→81.5；
- `Goal2Skill`：双系统 + 结构化记忆 + 恢复，RMBench 32.4% vs 9.8%；
- `LoHo-Manip`：trace-conditioned VLA、进度感知剩余计划、receding horizon；
- `RePO-VLA`：恢复驱动策略优化，对抗成功率 20→75；
- `Retrieve-then-Steer` / `RTCF`：成功记忆、进度校准检索、训练免费；
- `Foresight` / `ProbeAct`：世界模型 latent / 运行时失败检测与恢复。

但大多假设**进度单调**，或由 planner 自己产生子目标；它们没有「评估者故意 undo」的一等公民，也没有「官方评分表 + 部分分」的预算分配。

所以本轮的研究问题不是「做更长」，而是：**当环境可以把进度打回去时，单模型策略如何知道、如何回滚、如何用剩余预算重新完成？** 这就是 `Progress Belief + Undo Detection + Rollback`。

## 2. 榜单/头部方案给的真正信号

### 2.1 头部模型不是「更大」，而是「更懂具身」

| 模型 | 公开方法 | 强项 | 对 UniBot 的缺口 |
|---|---|---|---|
| MolmoAct2 | Molmo 2-ER 具身推理 VLM + flow-matching action expert + KV-cache bridge；adaptive depth | 空间 grounding 强；180ms 基础 / 790ms 自适应 | 无显式任务记忆/撤销恢复；重 |
| WALL-OSS-0.5 | 4B；3B VLM + action expert；20+ 形态、百万级轨迹；gradient-bridged 三目标预训练 | 跨形态泛化、部署就绪 | 单帧输入，时序记忆弱 |
| DreamZero | 14B World Action Model；视频扩散骨干；联合预测未来视频/动作；7Hz | 物理 OOD、零样本泛化 | 重、延迟高；精细接触精度未证 |
| DM0 | 2.4B 具身原生；Qwen3-1.7B + perception encoder + flow matching；空间 CoT | RoboChallenge 62.0% specialist / 37.3% generalist | 无运行时；通用任务适配未知 |
| Spirit-v1.5 | 5B；Qwen3-VL-4B + DiT；开放式多样数据 | Table30 曾第一；数据多样性红利 | 通用基座；无进程状态 |
| GigaBrain-0 | PaliGemma2 + DiT；世界模型生成数据 + RGBD + CoT | 泛化、长程 | 无运行时；依赖深度/数据 |
| π0.5 / GR00T N1.5 | 通用 VLA 基座 | 语义/动作先验强 | 单次动作生成；无显式步骤/撤销 |
| WLA-1.0-Base | 6B；Qwen-VL + DiT；2,500h 真机、64 任务；G1/Dex1；EE xyz_rpy；chunk 30@30fps | **具身最匹配**；Apache-2.0；24GB 可微调 | 不是 runtime；需要 UniBot 适配 |

### 2.2 共同缺口

1. **单次动作生成**：没有显式步骤状态；失败往往到最后才发现。
2. **不做撤销**：默认进度单调；真人可以把已完成步骤打回去。
3. **接触精度不足**：insert / zip / unscrew / hang / pour / pick-out 需要 guarded move、对准、验证；纯 chunk 策略容易在最后 1–3cm 失败。
4. **没有成功优先的预算**：180s、重试、验证时间没有按「成功关键路径 × 不确定性」分配。
5. **具身差异**：通用 VLA 在 Table30 强，不代表在 G1/Dex1 + 四路相机 + 现场人干扰下强。
6. **单模型约束**：不能 ensemble；runtime 必须是确定性代码 + 一个 checkpoint。

### 2.3 为什么这是机会

- 头部模型 2.4B–14B，算力不是唯一护城河；WLA-1.0-Base + 33k + 24GB 微调让小团队也能进入。
- 官方评分步骤 + human 备注公开；没有第二个 benchmark 给出这么细的运行时规格。
- 若公示表为真，底部任务集中在接触密集/精细操作（PlugInEthernet、Unlock、SpellRobot、OrganizeStationery、PourOutMedicine、HangCup、PickOutBatteries、ZipUp），且难度标签几乎不预测成功率（Easy 26.05 / Medium 24.67 / Hard 24.61）；这说明失败模式异质，**运行时专精**可能比继续堆一个单体策略更划算。
- 成功率与步骤分差约 8.6pp，说明「做到大部分、倒在最后/被撤销」常见；这正是 PB/回滚/接触技能的杠杆。
- **一句话：不要只 outscale，要 out-runtime。**

## 4. SCORE-OS 一句话与架构

```text
语言（32×5 复述之一）
        │
        ▼
Rubric Compiler：score_steps + 权重 + 谓词 + 技能槽
        │  → 任务进程图（步骤/边/终局/关键路径）
        ▼
Progress Belief：b_t(i)=P(step i done)，u_t=P(undo)
        │  ← 4×RGB + 本体 + 历史 + 技能结果
        ▼
Success-First Scheduler
   ├─ VLA：自由空间语义运动（WLA 唯一 checkpoint）
   ├─ SKILL：insert / zip / unscrew / hang / pour / pick-out / stack / close / hold / pivot
   ├─ VERIFY：多视角谓词 + 稳定检测
   ├─ ROLLBACK：撤销/失败 → 回到最后一个已验证步骤
   └─ STOP：安全/时间守卫
        │
        ▼
Verifier + Recovery：谓词保持、false completion、regrasp/nudge/retry
        │
        ▼
Session Memory：对象绑定、步骤历史、撤销事件、已验证状态
```

一句话：**把评分表当程序、把进度当进程状态、把技能当系统调用、把撤销当中断、把回滚当 checkpoint/restart。**

## 5. 为什么这是研究问题，不是工程堆叠

### 5.1 四个可发表的新意

1. **Rubric-native runtime**：把官方部分分评分表编译成调度器，而不是让 VLA 自己猜子目标。现有 agent OS 不做 benchmark rubric；现有 VLA 不做进程状态。
2. **Undo-aware progress belief**：显式建模「已完成步骤被打回去」，检测、回滚、重做。现有长程工作大多假设单调进度；UniBot 的现场人干扰提供了天然对抗测试。
3. **Contact-skill kernel under single-checkpoint**：技能是确定性/参数化控制器，不是第二个模型；WLA 负责自由空间与语义，技能负责最后接触。单模型约束下的 co-design 是新的。
4. **Success-first budgeted verification**：不是均匀重试，也不是按步骤分加权；按「成功关键路径 × 失败概率 × 可恢复性」分配 180s。这个目标函数与排名规则对齐。

### 5.2 与相关工作的差异

| 工作 | 进度状态 | 撤销 | 官方评分表 | 单 checkpoint | 接触技能 | 成功优先预算 |
|---|---|---|---|---|---|---|
| HELM | 有 memory/verifier/rollback | 未强调 | 否 | 未强调 | 否 | 否 |
| Goal2Skill | 有结构化记忆/恢复 | 未强调 | 否 | 否（双系统） | 有技能库 | 否 |
| LoHo-Manip | 有进度感知计划 | 未强调 | 否 | 否（planner+VLA） | 部分 | 否 |
| TypeGo / PhyAgentOS | OS runtime | 未强调 | 否 | 未强调 | 有 skill | 通用调度 |
| ProbeAct / Foresight | 失败检测/恢复 | 未强调 | 否 | 未强调 | 否 | 否 |
| **SCORE-OS** | **有** | **一等公民** | **是** | **是** | **是** | **是** |

这不是说别人做不到，而是**没有人为 UniBot 这个「官方评分表 + 现场人撤销 + 单模型 + 180s」的组合做 co-design**。

## 6. 可证伪假设与 kill criteria

| 假设 | 观测 | 失败即放弃 |
|---|---|---|
| H1：PB + undo 提升 human 轴成功率 | 调试槽/回放中 human 轴 +5pp 以上 | <2pp 或 undo recall <0.6 → 退回规则式谓词 |
| H2：接触技能提升终局成功率 | T10/T19/T27 终局 +10pp | <5pp → 技能只做安全兜底 |
| H3：成功优先调度优于均匀重试 | 同等 180s 下总分 +3pp 或超时更少 | 无增益 → 固定预算 |
| H4：WLA 微调本身能超过通用基座 | 调试槽/计分跑高于零样本 | 无增益 → 检查数据/接口 |
| H5：情感化复述是负对照 | 中性 vs 强调 Δ<2pp | Δ 大 → 语言 grounding 脆，记录但不转主投 |
| H6：运行时开销可接受 | p99 稳定、无安全终止 | 延迟/抖动大 → 降验证频率/技能数 |

**统计现实**：32×10=320 trials；总体 p≈0.3 时 SE≈2.56pp，独立两比例 80% power 的最小可检测差异约 **10.1pp**（配对 ρ=0.5 约 7.2pp）；单任务 10 trials 的 MDE 约 57.4pp [S1][S2]。所以：

- 不要用一次计分跑的 +3pp 证明胜利；也不要因一次 −3pp 否定方案；
- 真机调试槽用于**机制验证**（undo recall、接触成功率、false completion），不是统计显著；
- 计分跑用于**最终方向验证**，计划 2 次，报告均值/方差，不只看 best-of-multiple。

## 7. 风险与合规（先立后破）

- **榜单占位**：不据此调参；只当难度先验。
- **规则未读全**：手册 2.2 之后、截止日期、提交次数、外部数据、步骤分聚合公式未完全核实；默认保守。
- **单模型审计**：推理期只加载 WLA 一个 checkpoint；PB/verifier/recovery 头属于同一 checkpoint；技能/调度/几何是确定性代码；检索库是数据；推理期不用 SAM/FoundationPose/外部 VLM；模型卡逐项披露。
- **无力/无深度**：接触技能只能用位置控制 + 立体/腕部视觉 + 夹爪状态 + EE 位姿；不宣称力控。立体在 0.4–0.6m 可用（1px 视差约 1.0–2.2cm），1m 外只做粗定位。
- **现场真人**：人手进入工作区减速/停止；干扰结束后重新定位/回滚；安全终止不补测。
- **单日一槽**：真机只做发布门；离线/仿真/回放先过 gate；最多 3 次调试槽。
- **延迟/动作规律性被记录**：固定 chunk、固定预算、无动态模型切换；p99 稳定优先于峰值速度。
- **外部数据默认 OFF**：L2L 只在书面确认后开启；比赛期间不开源核心权重。
- **统计噪声**：320 trials 只能检测大效应；内部决策看机制指标与配对分析。

## 8. 一句话押注

**UniBot 的下一分不在更大的 VLA，而在把公开评分表编译成单模型策略的运行时：用进度信念检测人为撤销，用接触技能内核保证终局操作，用成功优先的预算调度在 180s 内完成会话。**

### 1.2 排名与统计功效

```text
任务得分 = 10 次成功率（两位小数） + 关键步骤分
模型得分 = 32 任务总平均成功率 + 总平均步骤分
排名 = 成功率 ↓，然后步骤分 ↓，然后提交时间 ↑
best-of-multiple = 取成功率最高的一次完整 32 任务计分评测
```

为什么不能把步骤分当主目标：

- 成功是 0/1 闸门；步骤分只在同成功率时破同分。
- 一个「0→1」的恢复，价值高于「60→80」的部分分。
- 步骤分仍有诊断价值：告诉我们失败发生在哪一步；但不能为了多做一个容易步骤而冒碰撞/超时风险。

统计功效（p≈0.3，独立两比例，80% power）[S1][S2]：

| 层级 | n | SE | 95% CI 半宽 | MDE（独立） | MDE（配对 ρ=0.5） |
|---|---:|---:|---:|---:|---:|
| 总体 | 320 | 2.56pp | ±5.0pp | **≈10.1pp** | ≈7.2pp |
| 单轴 | 64 | 5.73pp | ±11.2pp | ≈22.7pp | ≈16.0pp |
| 单任务 | 10 | 14.5pp | ±28.4pp | ≈57.4pp | ≈40.6pp |

**结论**：单次 320-trial 跑对 +3pp 几乎无统计力；不要用一次 +3pp 宣称胜利，也不要用一次 −3pp 否定方案。内部决策靠离线步骤级指标、配对/分层 bootstrap、调试槽机制验证；计分跑只做方向确认。best-of-multiple 还会放大「运气」，必须看均值/方差和安全终止。

### 2.2 公开真机基准的对照

- DM0 2.4B 在 RoboChallenge Table30 达 62.0% specialist / 37.3% generalist；
- Spirit-v1.5 5B 在 Table30 曾排第一；
- 这些成绩说明：**通用 VLA 在相近真机基准可以做到 37%+**。
- 如果 UniBot 榜单是真实的且只有 20–30%，更可能是：

### 2.3 瓶颈分类

| 编号 | 瓶颈 | 机制 | 对应组件 |
|---|---|---|---|
| B1 | 具身/跨机器人差异 | 相机位姿、桌高、个体差异；EE base 系动作不可直接迁移 | TaskFrame + 视觉伺服 + 重标定 |
| B2 | 接触密集精度 | insert/zip/unscrew/hang/pour/pick-out；无力/无深度；最后 1–3cm 失败 | Contact-Skill Kernel + 腕部视觉 |
| B3 | 进度/撤销 | 单次动作生成；真人撤销已完成步骤；false completion | Progress Belief + Undo + Rollback |

### 2.4 结论

- 头部模型是强感知/强语义的「单次动作生成器」，不是「多阶段会话管理器」。
- 在 UniBot，**B2+B3+B4** 是最未被满足、且最能用确定性 runtime 补的三块。
- 因此，SCORE-OS 不试图发明更强的 VLA；它把 WLA 放进一个**可验证、可回滚、按成功概率分配算力**的会话里。

## 3. 三个灵感词的裁决

### 3.1 机器人操作系统：policy-side runtime，不是 ROS

**接受，但重 framing。**

- G1 底层有 ROS 2/DDS，但评测只给 policy websocket API；不能起 ROS node、不能读 DDS、不能控底层。
- 所以 OS 抽象必须落在**策略进程内部**：评分表是程序，进度信念是进程表，技能是系统调用，调度器是 CPU 调度，撤销是中断，回滚是 checkpoint/restart，端口是地址空间。
- 这不是「套概念」：调度器会改变每一步的动作源和时间分配，直接改变成功率。

**相关工作**：

- `TypeGo`（SOSP 2026）：具身 agent OS runtime、skill kernel、异步规划、抢占；在 Unitree Go2 上验证。
- `PhyAgentOS`：session-centered runtime、语义验证、记忆；面向长程具身。
- `rosaOS`：OS-inspired、MCP + ROS；面向 LLM agent 与机器人技能。
- Nature MI 2026：LLM + ROS 框架、behavior tree、skill learning、reflection。
- 这些工作证明 OS 抽象有效，但它们不是为「官方评分表 + 单模型 + 部分分 + 现场撤销」设计，也通常假设能调工具/多模型/有机器人 OS 权限。

**差异**：

1. **benchmark-native**：Rubric Compiler 直接吃 `score_steps`，不是自由 planner。
2. **single-checkpoint**：没有第二个 VLM/planner；PB/verifier 头在 WLA 内。
3. **undo-first**：现场撤销是一等中断，不是异常。
4. **success-first budget**：按成功关键路径分配 180s，不按步骤分加权。

### 3.2 情感语音：明确剪枝

**不要。**

- API 无音频、无麦克风、无 prosody；`observation.language` 是 episode 内固定字符串。
- `VLAS`/`AffectLoop` 等工作无法接入；加 speech encoder 是死通道，违反接口/单模型/延迟。
- 唯一合法残留：**文本负对照**——中性 vs 强调/情绪化复述，测语义不变性；Δ<2pp 是预期，Δ大则记录语言 grounding 脆弱，但不转主投。
- 真正与「人」有关的信号是 **human 轴的现场撤销**，不是语音情感。

### 3.3 长程任务：long-horizon in the small

**接受，但重新定义。**

- 32 任务 2–5 步、6–10s 演示、180s 上限：按传统时长不算长。
- 但现场人可以把已完成步骤打回去：T27 叠了第二个又拿下、T19 拉上又拉开、T14 拧开又拧回、T17 合上又打开、T10 拔起插头、T12 拿走锁、T24 放回起点、T16 翻开毛巾。
- 所以它是 **100–1000 控制步、2–5 语义步、进度非单调、成功 0/1、部分分** 的「小长程」。
- 现有长程工作（HELM/Goal2Skill/LoHo/RePO/ProbeAct/Foresight）提供 memory/verifier/rollback/failure detection，但大多假设进度单调，或没有官方评分表/现场撤销。
- 我们的研究问题：**当环境可以 undo 时，单模型如何知道、回滚、用剩余预算重做？**

## 4. SCORE-OS 架构

### 4.1 设计原则

1. **成功优先**：`P(success)` 是主目标；步骤分只做 tie-break/诊断。
2. **评分表原生**：所有步骤/权重/终局谓词来自官方 `info.json`，不自由发明子目标。
3. **撤销一等**：进度可下降；检测→回滚→重做是正常路径。
4. **单 checkpoint**：WLA 是唯一学习模型；PB/verifier/recovery 头在同一 checkpoint；技能/调度/几何是确定性代码。
5. **接触有界**：技能是参数化控制器，限速/限域/可停止；不宣称力控。
6. **会话隔离**：每机器人/每端口独立状态；`reset()` 清空 PB/历史/技能状态。
7. **延迟稳定**：固定 chunk、固定预算、无动态模型切换；p99 稳定优先。

### 4.2 总览

```text
┌──────────────────────── Offline（训练/标定）─────────────────────────┐
│ 官方 33k（LeRobot v3，4×RGB，EE base，5 复述，无 depth/force）          │
```

### 4.3 控制循环

```python
def run_episode(obs_stream, task, budget=180.0):
    rubric = RubricCompiler(task)          # 官方 score_steps + 5 复述
    session = Session(rubric, budget)
    belief = ProgressBelief(rubric)
    memory = SessionMemory()

    while not session.done:
        obs = obs_stream.get()             # 4×RGB + proprio + language
        belief.update(obs, memory)
        memory.update_objects(obs, belief)

        if belief.undo_detected():
            session.rollback(belief.undone_step)
            memory.log_undo(belief.undone_step, cause=belief.undo_cause)
            continue

        action = scheduler.choose(belief, memory, session)
        if action.type == "STOP":
            break
        if action.type == "VERIFY":
            result = verifier.check(obs, action.step, memory)
            belief.update_verification(action.step, result)
        elif action.type == "ROLLBACK":
            session.rollback(action.step)
        elif action.type == "SKILL":
            result = skill_kernel.execute(action.skill, obs, belief, memory)
            belief.update_skill(action.step, result)
        else:  # VLA
            chunk = policy.act(obs, action.context)   # 唯一 checkpoint
            send(chunk)                              # 评估器执行完整 chunk
            belief.update_action(action.step, chunk)

        if belief.step_done(session.current) and verifier.confirm(session.current):
            memory.mark_verified(session.current)
            session.advance()

    return session.score
```

### 4.4 chunk 与延迟

- `action_chunk_size` 是提交级固定值；评估器执行完整 chunk 后才再次调用。**验证/撤销检测/技能切换只能发生在 chunk 边界。**
- 接触任务建议 chunk **8–12**（0.27–0.40s）；自由空间可 16–30。由于固定值，首版建议 **8**，用 WLA 微调/前缀截断适配；若延迟/平滑不达标，改 12/16 做消融。
- 6B 模型 p99 目标：不超过 chunk 时长（chunk 8 ≈267ms）；具体以实测为准。若 p99 超时，优先降验证频率/图像分辨率，而不是动态换模型。
- 动作必须 well-formed、平滑；避免异常离群；官方会记录延迟/波动/动作规律性。

### 5.3 语言匹配

- 32×5=160 条官方复述 → 精确匹配 + 规范化（小写/去标点/去冠词）+ 规则关键词；
- 未见复述 → 用 WLA 的文本特征做相似度（同一 checkpoint，不加载外部模型）；
- 匹配失败 → 用任务 ID/场景对象做保守 fallback，不要猜错步骤图。
- **注意**：评测指令可能是 5 条之一，也可能是未见复述；状态机要能容忍同义表达，不能只靠精确字符串。

### 5.4 成功优先的目标函数

```text
主目标：max P(all steps complete)
次目标：max E[Σ w_i * 1_i]        # 只用于同成功率 tie-break / 验证优先级
约束：T ≤ 180s；安全；单 checkpoint；无外部模型
```

**重要**：不要用 `Σ w_i` 当主奖励。一个高权重终局步骤如果已经大概率成功，继续投入验证的边际收益低；一个低权重早期步骤如果失败，会让整条 episode 归零。调度应按**成功关键路径 × 失败概率 × 可恢复性**，不是单纯按权重。

## 6. Progress Belief 与 Undo Detection

### 6.1 定义

对任务 `t` 的步骤 `i=1..k`：

```text
b_t(i) = P(step i complete | o_1:t, a_1:t, history)
u_t    = P(an already-complete step was undone at t | ...)
c_t    = cause ∈ {human_move, robot_drop, occlusion, false_completion, none}
```

- `b_t(i)` 允许**下降**：这是与单调进度估计的本质区别。
- `u_t` 检测撤销；`c_t` 区分原因，决定恢复策略。
- `P(success) ≈ Π_i b_t(i)` 仅作粗估计；实际用校准后的联合头/规则。

### 6.2 架构

- 输入：4 路 RGB（或 3 路：左高 + 双腕）、EE 位姿、夹爪、`lower_body`、上一动作、步骤 ID、历史摘要。
- 主干：WLA 的 VLM/视觉特征（冻结或 LoRA）+ 轻量时序头（2 层 Transformer/GRU）。
- 输出：
  - 每步完成 logit；
  - 对象状态（held/on/in/closed/inserted/zipped/stable）；
  - 撤销 logit + 原因分类；
  - 置信度/校准。
- 训练：多任务（步骤完成 + 对象状态 + 撤销 + 失败检测）；focal loss 处理类别不平衡；temperature scaling 校准（ECE <0.1）。
- 推理：每个 chunk 边界更新一次；不加载外部 VLM。

### 6.3 标签

- **步骤完成**：用 `score_steps` + 演示相位切分（TLE）自动标注；人工抽检 10%。
- **接触段**：夹爪开合、EE 速度、腕部视觉接触、物体位移。
- **撤销**：
  - human 备注提供**意图**（不是逐帧脚本）；
  - 合成反向扰动：在仿真/回放中把已完成步骤的对象移回/打开/拔起；
  - 真实现场人干扰作为最终测试。
- **双手角色**：从步骤文本/任务描述启发式标注 anchor/actor；少量人工校正。
- **false completion**：谓词从 1→0、物体掉落、插入未到位、拉链未闭合。

### 6.4 更新与回滚

```text
if verifier confirms step i:
    b_t(i) = max(b_t(i), τ_done)
if b_t(j) drops below τ_undo for j < current:
    u_t = 1; rollback to j; invalidate b_t(l) for l > j
if b_t(i) high but verifier false:
    c_t = false_completion; do not advance; verify again / retry
```

- `τ_done` / `τ_undo` 由校准集调；不要用单一阈值，按任务/技能分桶。
- 回滚不是「重新开始」：回到最后一个**已验证**步骤，保留对象绑定；只重做受影响的下游。
- 如果人手正在移动对象：先安全等待/停止；人离开后重新定位，再决定重做/继续。
- 如果机器人自己掉了物体：`regrasp`，不回滚整个任务。
- 如果遮挡导致 `b` 下降：先移动腕部/头部验证，不要误判 undo。

### 6.5 评估

- 步骤完成 F1 / AUROC / ECE；
- undo precision/recall、检测延迟（chunk 数）；
- false completion rate；
- 回滚后恢复成功率、恢复时间；
- 与规则式谓词基线对比。

## 7. Contact-Skill Kernel（接触技能内核）

### 7.1 为什么需要

- 底部任务集中在接触密集/精细操作（若公示表为真），且通用 VLA 在最后 1–3cm 容易失败。
- API 无力/无深度；不能做真实力控，只能用**位置控制 + 立体/腕部视觉 + 夹爪状态 + EE 位姿**。
- 技能是**参数化控制器**，不是第二个学习模型；参数从演示/离线调参/仿真获得。
- 单模型合规：技能是确定性代码，WLA 是唯一 checkpoint。

### 7.2 技能表

| 技能 | 任务示例 | 前置 | 控制器 | 终止/验证 | 恢复 |
|---|---|---|---|---|---|
| `place` | T02/T03/T04/T06/T08/T13/T15/T21/T25 | holding, target frame | EE 到目标位姿；减速；缓放 | 谓词 on/in + 稳定 | nudge / regrasp / re-place |

| `zip` | T18/T19/T23/T31 | tab grasp, track visible | 抓 tab；沿轨道小步拉；保持方向 | 闭合谓词 + 轨道终点 | 重抓 / 回退 / 重拉 |

### 7.3 双手 hold/act

- 至少 15 个任务很可能需要「一臂持稳 + 一臂操作」；T05/T26 的步骤文本直接写 "Hold the network port"。
- 运行时给两臂分配 **anchor（hold）** 与 **actor（operate）**；anchor 低增益保持，actor 在相对系里执行。
- 视觉伺服修正 anchor 漂移；限幅；异常时退回纯 VLA/停止。
- 这是接触技能内核的一部分，不新增学习模型。

### 7.4 无力/无深度的实现边界

- **insert**：视觉对准 + 小步轴向进给 + 螺旋搜索；用腕部图像/夹爪状态/EE 位姿判断到位；不用力控。
- **zip**：抓 tab + 沿轨道小步拉；用视觉轨道/闭合谓词判断；不用力控。
- **unscrew**：腕部旋转 + 小步提升；用视觉/盖子分离判断；不用力矩。
- **pour**：倾斜 + 腕部视觉液面/流量；不用称重。
- **hold**：低增益位置保持 + 视觉伺服；不宣称阻抗控制。
- 立体只做 0.4–0.6m 粗几何；精细对准用腕部单目 + 已知尺寸/视觉伺服。
- 如果任务需要力控而 API 不提供，明确标「不可靠」，用视觉/重试兜底，不吹。

### 7.5 与 VLA 的交接

```text
VLA 自由空间接近 → 进入接触区 → Scheduler 切 SKILL
SKILL 执行 → Verifier 确认 → 释放/退出 → 切回 VLA 下一步
SKILL 失败 → Recovery：retract/regrasp/retry → 仍失败 → ROLLBACK
```

- 交接条件：EE 到预接触位姿、目标可见、夹爪状态正确、置信度足够。
- 技能执行期间仍用 WLA 的视觉特征/谓词头做监控；不另起模型。
- 安全：工作空间、最大步长、速度、碰撞接近、人手接近停止。

## 8. Success-First Session Scheduler

### 8.1 目标

```text
J(a) = P(success | a) + ε * E[partial | a] - λ * T(a) - μ * risk(a)
a ∈ {VLA, SKILL(s), VERIFY, ROLLBACK, STOP}
```

- `P(success)` 主项；`E[partial]` 只做 tie-break/诊断（ε 小）。
- `T(a)` 预计耗时；`risk(a)` 碰撞/安全/超时风险。
- 所有决策在 chunk 边界；不在 chunk 内切换。

### 8.2 规则式首版

```text
if safety_risk or time_left < reserve: STOP
if undo_detected: ROLLBACK(undone_step)
if current step is contact and skill available and skill_conf > τ_skill: SKILL
if belief uncertain on critical step and time allows: VERIFY
if repeated failure >= 2: ROLLBACK / regrasp / restart_step
else: VLA
```

- **VERIFY 的价值**：`criticality_i * entropy(b_i) - cost_verify`；只对成功关键路径且高不确定的步骤验证。
- **重试预算**：按失败概率 × 可恢复性分配，不按步骤权重单独分配；终局步骤预留验证时间。
- **时间守卫**：180s；预留 10s 收尾/停止；长任务（T16/T17/T31）限制重试次数。
- **成功优先**：如果时间不够，优先保证当前步骤完成/回滚到可完成路径，不为了多拿部分分冒险。

### 8.3 为什么不是 RL 首版

- 真机反馈稀缺（单日一槽）、统计噪声大；RL 探索风险高。
- 规则式可解释、可审计、延迟稳定；先验证机制，再考虑学习调度。
- 如果后期学习，调度头可以放进同一 checkpoint，但仍需确定性兜底。

### 8.4 预算示例

```text
总预算 180s
├─ 自由空间运动/抓取：~50%
├─ 接触技能：~30%
├─ 验证/稳定：~10%
├─ 回滚/重试：~10%
└─ 安全余量：10s
```

实际按任务/步骤动态调整；接触任务多一点技能/验证，长任务少一点重试。

## 9. Verifier 与 Recovery

### 9.1 谓词

| 谓词 | 含义 | 证据 |
|---|---|---|
| `holding(x)` | 夹爪持物 | 夹爪开度 + 腕部视觉 |
| `on(x,y)` | x 在 y 上 | 多视角几何 + 稳定 |
| `in(x,y)` | x 在 y 内 | 容器口/内部可见性 + EE 位姿 |
| `closed(x)` | 盖子/拉链闭合 | 视觉 + 几何 |
| `inserted(x,y)` | 插头/网线到位 | 插入深度/连接视觉 |
| `zipped(x)` | 拉链闭合 | 轨道终点/齿合视觉 |
| `hanging(x)` | 挂在钩/架上 | 钩-柄关系 + 稳定 |
| `poured(x,y)` | 倒出/转移 | 液面/流量/目标杯 |
| `stable(x)` | 释放后稳定 | 0.5s 位移 <ε |
| `clear(x)` | 路径无障碍/无人手 | 立体/视觉 |

### 9.2 多视角验证

- head stereo + 双腕；遮挡时移动腕部/头部到验证位姿，再检查。
- 立体用于桌面/容器粗几何；腕部用于接触细节。
- 不用外部 VLM/检测器；用 WLA 特征/小头 + 经典几何。
- 如果立体不可信（透明/低纹理），退回腕部视觉 + 谓词头；不确定时**不前进**。

### 9.3 稳定性与 false completion

```python
def verify_and_settle(step, obs, memory, budget=2):
    for attempt in range(budget + 1):
        if not verifier.predicate(step, obs):
            return False
        release_slowly()
        sleep(0.5)
        if verifier.stable(step, obs, window=0.5):
            return True
        if verifier.repairable(step, obs):
            nudge(step)
        else:
            regrasp(step)
    return False
```

- `stable`：物体相对位姿 0.5s 内位移 <ε（由演示统计给出）+ 谓词保持。
- false completion：PB 高但 verifier 低 → 不前进；PB 低但 verifier 高 → 再验证一次。
- 释放后掉落/弹跳/滚动：nudge/regrasp/re-place；预算内重试。

### 9.4 回滚

- 回到最后一个**已验证**步骤；保留对象绑定；只重做受影响的下游。
- 如果人手移动了对象：重新定位/更新 TaskFrame；如果机器人正持物，先安全保持/停止。
- 如果机器人自己掉了：regrasp，不回滚整个任务。
- 如果连续失败 2 次：回滚一步；仍失败：restart_step；时间不够：STOP 安全。
- NRB：用 human 备注意图 + 合成 undo 生成恢复对，训练 recovery 头；不把备注当精确脚本。

## 10. WLA 微调与数据引擎

### 10.1 底座选择

- `WLA-1.0-Base` 6B，G1/Dex1 原生，Apache-2.0，2,500h，64 任务，EE `xyz_rpy`，24GB action expert 微调。
- 预训练任务含 HangCup/Stack_Block，与 UniBot T01/T27 重叠；先检查数据泄漏/分布重叠，再决定是否冻结部分层。
- 对比基线：WLA 零样本、WLA 仅 action expert 微调、WLA + LoRA、WLA + 全参（若算力允许）。

### 10.2 模型改造

- VLM 冻结（默认）；action expert/DiT + projector 微调；LoRA 可选。
- 新增小头（与 action expert 共享特征）：
  - `PB head`：每步完成 logit + 对象状态 + 撤销 logit/原因；
  - `Verifier head`：谓词/稳定/false completion；
  - `Recovery head`：regrasp/nudge/retry/rollback 选择（可与规则融合）。
- 所有头属于**同一 checkpoint**；推理只加载一个模型。
- 图像：WLA 用 336×448；挑战 480×640，评估器可 resize；首版 3 视图（左高 + 双腕），右高作立体/备用。
- 动作：EE `[6]` + gripper + `action.pivot[7]`；WLA 的 waist/base/legs 映射到挑战 pivot 需验证语义（绝对/增量未知）。
- chunk：WLA 预训练 30；挑战首版 8；微调时用短 chunk 或前缀截断；测试平滑/延迟。

### 10.3 数据

| 数据 | 用途 | 规模 |
|---|---|---|
| 官方 33k / 169h | action expert 微调、PB/verifier 标签 | 32 任务 × ~1k |
| 步骤相位/接触段 | PB/技能/验证 | TLE 自动 + 10% 抽检 |
| human 备注 | undo 意图/场景 | 32 任务 × 2 条左右 |
| 合成 undo | PB/recovery 训练 | 反向扰动/回放/仿真 |
| L2L 实验室 | 背景/位置多样性 | 可选，默认 OFF；3 实验室 ×2 任务 ×100–200 |
| 合成 2.5D | 背景/干扰物/位置 | ACP/GF；不做全物理 |

- 不做全 32 任务高保真孪生；只对 3–5 个代表任务做仿真闭环（T10 插入、T19 拉链、T27 堆叠、T12 开锁）。
- 合成数据不主导；GF 软权重；真实 held-out 监控负迁移。
- 外部数据默认 OFF；书面确认后开；比赛期间不开源核心权重。

### 10.4 训练课程

| 阶段 | 数据 | 目标 | 退出 |
|---|---|---|---|
| 0 | 官方 100% | 复现 WLA 基线 | held-out 不降 |
| 1 | +步骤/接触标签 | PB/verifier 起步 | 步骤 F1 >0.7 |
| 2 | +短 chunk | 适配 8–12 | 平滑/延迟达标 |
| 3 | +合成 undo | undo recall >0.6 | false completion <10% |
| 4 | +技能段 | 接触技能成功 | 调试槽 +5pp |
| 5 | +恢复对 | 回滚恢复 >50% | 无安全终止 |
| 6 | 全量 + 量化/蒸馏 | 部署 | p99 稳定 |

### 10.5 算力

- action expert 微调：单卡 24GB 可跑；多卡 8×H100 2–3 周。
- PB/verifier/recovery 头：额外显存；建议 40–80GB 或 LoRA/冻结；先用小头 + 共享特征。
- 数据预处理/缓存：33k × 4 相机，存储/IO 是瓶颈；resize 到 336×448，缓存。
- 推理：6B + 短 chunk；p99 目标 ≤ chunk 时长；必要时量化/蒸馏，但不要动态换模型。

### 10.6 单模型审计

- 推理进程只加载一个 WLA checkpoint；PB/verifier/recovery 头在同一 checkpoint。
- 技能/调度/几何/状态机是确定性代码；检索库（若用）是数据。
- 推理期不用 SAM/FoundationPose/GroundingDINO/外部 VLM；这些只做离线标注/质检。
- 模型卡逐项披露：模型、头、技能、检索、外部数据、训练数据。
- 如果主办方判定确定性技能/经典 CV 也算“模型”，退回纯 WLA + 规则式 SSG/SVL；不要隐瞒。

## 11. 实验与评测

### 11.1 研究问题

- **RQ1**：Rubric-native runtime + PB/undo 是否比强 WLA 微调基线在 human 轴/整体成功率上更好？
- **RQ2**：接触技能内核是否在 contact-rich 任务上显著优于 VLA-only？
- **RQ3**：成功优先调度是否比均匀重试/验证在 180s 内更优？
- **RQ4**：单 checkpoint + 确定性技能是否能跨机器人/背景/位置泛化，而不依赖外部模型？
- **RQ5**：情感化复述是否只是负对照（Δ<2pp），还是语言 grounding 脆弱的信号？

### 11.2 实验矩阵

| ID | 配置 | 目的 |
|---|---|---|
| E0 | WLA 零样本 | 底座下限 |
| E1 | WLA 微调 33k | 具身适配收益 |
| E2 | E1 + Rubric Compiler | 状态机/防跳步 |
| E3 | E2 + PB/undo | 撤销检测/回滚 |
| E4 | E3 + Contact-Skill Kernel | 接触精度 |
| E5 | E4 + Verifier/Recovery | false completion/稳定 |
| E6 | E5 + Success-First Scheduler | 预算分配 |
| E7 | E6 + TaskFrame/OPT | 几何/放置 |
| E8 | E7 + Retrieval（可选） | 上下文增益/延迟 |

### 11.3 指标

- 主：任务成功率、32 任务总平均成功率。
- 次：步骤分、步骤级完成率、undo recall/precision、false completion、恢复成功率、恢复时间、time-to-complete、重试次数、安全终止、延迟 p50/p99/jitter、动作平滑度。
- 诊断：任务×轴热力图、失败分类（B1–B6）、PB 校准（ECE）、接触技能分任务成功率、双手协调误差。

### 11.4 消融

- PB on/off；undo detection on/off；技能 on/off；每个技能单独 off；verifier on/off；scheduler uniform vs success-first；chunk 4/8/12/16/30；EE vs joint；3 vs 4 相机；立体 on/off；TaskFrame on/off；retrieval on/off；外部感知 off（合规）。
- 统计：配对/分层 bootstrap；任务级 partial pooling；报告均值±方差；不只看 best-of-multiple。

### 11.5 真机协议

- **离线**：held-out 演示、步骤 F1、undo 注入、技能回放；每天。
- **仿真**：3–5 任务（T10/T19/T27/T12/T14），注入 undo/人手移动；相对比较，不做 sim2real 绝对承诺。
- **调试槽**：每天最多 1 次；最多 3 次；只做发布门。
  - Slot #1：T27（堆叠）或 T10（插入）；验证技能/PB。
  - Slot #2：T19（拉链）或 T12（开锁）；验证接触/撤销。
  - Slot #3：T10/T27 复验；准备计分。
- **计分跑**：2 次（W7/W8）；报告均值/方差；安全优先。
- **Gate**：离线指标不达标不约真机；真机 <5pp 不烧计分跑；安全终止立即回退。

### 11.6 统计与解释

- 320 trials 只能检测 ~10pp 总体差异；调试槽单任务 10 trials 的 MDE ~57pp；所以：
  - 不要用单任务 10 次证明 +10pp；
  - 用步骤级/机制指标做迭代；
  - 计分跑只做方向确认；
  - best-of-multiple 看均值/方差，不只看最好一次。

## 12. 创新点清单（持续迭代）

> 状态：押注=本轮主线；保留=沿用；升级=旧点改造；可选=资源允许；砍=不做。

### I1 Rubric Compiler（升级 SSG｜押注）

- 动机：官方 `score_steps` 公开；成功优先；调度器需要进程图。
- 差异：不是被动状态机，而是编译权重/终局/谓词/技能槽，驱动调度。
- 可行性：确定性代码；32 任务 + 160 复述；无需训练。
- 资源：1 人周；CPU。
- 步骤：解析 → 图 → 类型/技能 → 谓词 → 单测。
- 风险：语言未覆盖、步骤顺序/权重错误；用官方 JSON + 抽检。

### I2 Progress Belief + Undo（新增｜押注）

- 动机：现场人撤销已完成步骤；单次 VLA 无进度状态；false completion。
- 差异：显式 `b_t(i)` 可下降 + `u_t` + 原因分类 + 回滚；不是单调进度。
- 可行性：演示/备注/合成 undo 标签；小头；WLA 特征。
- 资源：2–3 人周；8×H100；数据标注。
- 步骤：标签 → 头 → 校准 → undo 合成 → 集成。
- 风险：标签噪声、类别不平衡、误报；分桶阈值 + 人工抽检。

### I3 Contact-Skill Kernel（新增｜押注）

- 动机：接触密集任务底部；无力/无深度；VLA 最后厘米不稳。
- 差异：确定性参数化技能 + 单 checkpoint；视觉/几何；可验证/可回滚。
- 可行性：演示接触段；EE 动作；30Hz；无需第二个模型。
- 资源：3–4 人周；仿真/真机。
- 步骤：技能表 → 分段 → 实现 → 调参 → 验证。
- 风险：过拟合任务、无力控、sim2real、安全；分桶 + 限幅 + 回退 VLA。

### I4 Success-First Scheduler（新增｜押注）

- 动机：排名成功优先；180s；失败异质；均匀重试浪费。
- 差异：`P(success)` 主目标 + 验证价值 + 预算；不是按步骤分加权。
- 可行性：规则式；PB/技能统计；无训练。
- 资源：1–2 人周。
- 步骤：状态/动作/成本 → 阈值 → 集成 → 消融。
- 风险：短视、阈值难调、延迟；规则兜底 + 离线校准。

### I5 Verifier + Recovery/Rollback（升级 SVL/NRB｜押注）

- 动机：终局是闸门；false completion；撤销。
- 差异：多视角谓词 + 稳定 + 回滚 + session memory；不是单次释放。
- 可行性：WLA 特征/小头 + 几何；无外部模型。
- 资源：2–3 人周。
- 步骤：谓词 → 标签 → 验证 → 回滚 → 恢复。
- 风险：遮挡、误报、耗时；不确定不前进 + 时间守卫。

### I6 OPT/PGL 放置（保留｜技能）

- 动机：K 条演示的相对释放位姿统计；零梯度。
- 差异：现在是 `place/stack` 技能的先验，不是全局主叙事。
- 可行性：EE 位姿 + 容器几何；TaskFrame。
- 资源：1–2 人周。
- 风险：透明/软容器；分桶回退。

### I7 TaskFrame（保留 SPARC｜工具）

- 动机：跨机器人/桌面/容器移动；接触/放置需要几何底座。
- 差异：轻量立体/桌面/EE 坐标；不做全点云 atlas。
- 可行性：head stereo 已校正；0.4–0.6m 粗几何；腕部精细。
- 资源：1–2 人周。
- 风险：透明/低纹理、标定误差；回退腕部/VLA。

### I8 WLA 多任务微调（保留｜核心）

- 动机：G1/Dex1 原生；24GB；2,500h；任务重叠。
- 差异：action expert + PB/verifier/recovery 头；单 checkpoint。
- 可行性：官方文档；33k；LoRA。
- 资源：8×H100 2–3 周；24GB 最低。
- 风险：过拟合、遗忘、短 chunk、显存；分阶段 + held-out。

### I9 L2L / DebugLoop（保留｜程序）

- 动机：背景/位置多样性；真机发布门。
- 差异：逐字段协议 + QA + 合规 + 单日一槽纪律。
- 可行性：高校 G1 网络；平台调试；外部数据待确认。
- 资源：协调 2–3 人；3 次槽。
- 风险：规则、硬件、成本；默认 OFF + 书面确认。

### I10 情感语音负对照（砍｜负对照）

- 动机：三词之一；API 无音频。
- 差异：只做文本强调复述测试，不做模型。
- 资源：0.2 人周。
- 状态：砍；记录 Δ，不转主投。

### 已砍清单

- 全 32 任务高保真孪生；自由仿真数据；运行时仿真/MPC；仿真 RL。

## 14. 8 周计划（按单日一槽/统计噪声约束）

| 周 | 目标 | 交付 | Gate |
|---|---|---|---|

**里程碑**：

- M1（W1）：评分表编译 + 语言覆盖。
- M2（W3）：PB/undo 离线达标。
- M3（W5）：调试槽终局 +5pp。
- M4（W6）：接触/撤销 +10pp。
- M5（W7）：计分跑方向确认。
- M6（W8）：冻结/合规。
