# 第 9 轮（研究循环第 3 轮）· DUET：协同是铰链，灵巧是虚拟的，演示是剧本

> 检索/复核日期：**2026-10-25（UTC）**。赛事身份不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（`unibot.unitree.com`），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署、官方远程真机 API 评测。本轮三个灵感词是「协同控制」「灵巧手」「演示数据」。我先用官方手册、32 份任务 JSON、HF 全量数据和 5 个任务的逐帧统计把三个词各自钉到事实上，再给出主判断：**官方把「抓取、放置、双手协调」并列为三大能力；Dex1 只有 1-DOF，所以真正的灵巧不在手指，而在双手角色、相位、夹爪孔径、环境夹具与重抓；33k 同步演示正好是协同语料，官方 human 备注正好是协同扰动剧本。PILOT 把放置当闸门是对的，但协同是让闸门可达的铰链。** 方案名 **DUET**（Dual-arm Unified Execution with Temporal coordination）：BCC 协同编译器 + VDX 虚拟灵巧 + CRM 协同富集演示挖掘 + CSR 运行时协同监督 + CPE 协同扰动引擎 + MCAE 模式/角色条件动作专家 + ACG 孔径条件抓取 + CCPL 跨任务协同原语库；PILOT 的 SSG/PGL/OPT/SVL 保留为终局层，NRB 升级为官方剧本回放。

## 0. 本轮先核实/纠正的七个事实

### 0.1 排名公式：成功率优先，步骤分只是 tie-break

官方中文手册写得很清楚：**实时榜单按 32 个任务的总平均成功率排序；成功率相同时按总平均步骤分排序；仍相同则提交日期早者靠前**（[S1]，英文版 [S2] 同义）。这直接修正了上一轮的一个隐含权重：上一轮把「放置类步骤约占 59.7% 步骤分」当成主收益，方向对，但权重错。终局放置仍然重要，理由要改写：

```text
上一轮：终局放置重要，因为它占步骤分 39.8% / 放置类约 59.7%
本轮：  终局放置重要，首先因为它决定 binary success；
        步骤分是诊断、恢复信号与 tie-break，不是主 objective。
```

这意味着：**任何只提高部分步骤、但不能把 episode 从 fail 变成 success 的模块，都应降权**；而「让一个 0% 任务开始有成功」「human 轴撤销后能恢复」「双手支撑不丢」这类能力，权重上升。SSG 保留，但从「部分分优化器」改成「相位诊断 + 恢复触发器」。

### 0.2 「榜首不到 30%」目前是占位数据，不是真实榜单

截至 **2026-10-25**，`leaderboard.html` 仍显示「即将发布 / Coming Soon」，`runs.html` 仍是 `256 / 256` 条占位记录（[S9][S10]）。但 `leaderboard_data.json` 里已经有一份可读的 8 模型数据：榜首 `MolmoAct2 / DexHacker` 成功率 **29.7%**、步骤分 **39.0**、平均时长 **44.02s**；其后 `WALL-OSS-0.5` 28.5/38.9、`DreamZero` 27.9/37.9、`spirit` 25.9/34.4、`DM` 23.5/31.7、`PI` 22.8/30.6、`GigaBrain` 22.6/29.5、`GR00T` 20.5/28.1（[S9]）。用户说的「榜首成功率也不到 30%」与 29.7% 完全吻合，因此**它很可能来自这份占位数据，而不是真实评测**。

这份数据还有三个「占位」证据：

1. `generated_from: gen_leaderboard.py`，是脚本生成；
2. 任务命名与官方 slug/任务名不完全一致（如 `Clear Plates` vs `ArrangePlates`、`Store Racket` vs `StorePaddle`、`Stack Cups` vs `StoreCups`）；
3. 详情页视频明确写「测试视频占位，后续可替换为真实视频文件」（[S9]），`runs.html` 也是 8 模型 × 32 任务的 256 条占位记录（[S10]）。

所以本轮不把「<30%」当事实，而把它当**待验证假设**：如果真实榜首确实 <30%，最可能的瓶颈不是模型容量，而是「闭环协同 + 终局验证 + 人为撤销后的恢复」；如果真实榜首高于 30%，说明公开基线族中被低估的工程/数据因素在起作用，DUET 仍是增量，但收益上限要重估。占位数据只有一个可谨慎使用的量：8 个模型的步骤分平均比成功率高约 **7–10pp**（39.0 vs 29.7、38.9 vs 28.5、……28.1 vs 20.5），暗示「大部分失败发生在做完大部分步骤、倒在最后一步」；但必须标注「未核实」。

### 0.3 Dex1-1 不是灵巧手，而是 1-DOF 平行夹爪

`https://www.unitree.com/Dex1-1/` 的产品页给出（[S11]）：

- **1-DOF 平行夹爪**，不是五指灵巧手；
- 行程 **90mm**，夹持力 **5–120N 可调**；
- 指尖重复定位分辨率 **0.1mm**，全行程闭合 **0.24s**，控制频率 **1000Hz**；
- 夹爪长 **80mm**；宣传语是「form-fit 20kg / friction 5kg」，不是 finger-level dexterity。

数据集里 `observation.state.left_gripper` 与 `right_gripper` 各只有 **1 维**（开度），`action.left_gripper/right_gripper` 同样只有 1 维（[S6]）。这推翻了把「灵巧手」直接理解成「多指手内操作」的直觉：**在 UniBot 里，灵巧性必须由双手协同、环境接触、夹爪孔径和重抓来“虚拟”出来**。这不是退而求其次，而是任务本身的物理约束：

- 插头/网线/针管/拉链都需要**支撑手 + 操作手**；
- 碗/杯子/托盘需要**同相搬运**或**交替堆叠**；
- 毛巾/笔袋/耳机盒需要**双手压住 + 重抓**；
- 没有手指，就用桌面、架子、另一只手当“外部手指”。

### 0.4 全量数据已经发布：33k episodes / 169h，是协同语料而不是普通模仿语料

HF collection `unitreerobotics/unibot-v1-challenge-dataset` 的 32 个数据集，每个约 **970–1,530 条**，合计约 **33,276 episodes / 18.28M 帧 / 169h**，Apache-2.0（[S5][S6]）。实测：

| 数据集 | episodes | frames | 备注 |
|---|---:|---:|---|
| `G1_Dex1_HangCup` | 1,043 | 194,564 | `lastModified` 2026-10-14 |
| `G1_Dex1_ArrangePlates` | 1,069 | 683,859 | 四条相机流 |
| `G1_Dex1_StackBowls` | 979 | 295,609 | 30fps |

所有数据集采用 LeRobot v3.0：4 路 480×640 相机（head_stereo_left/right + wrist_left/right）、左右臂各 7 DoF、左右夹爪各 1 维、EE pose 在 base 与 torso 两套坐标里都有、`lower_body` 15 维、`waist_state_joint` 3 维、`recomputed_ee_valid` 1 维；`action` 侧还有 `action.pivot[7]`、`action.gripper_controls[4]`、`action.base_command[4]`（[S6]）。旧预览只有 44 条（2026-08-18 社区帖），现在可以确认**全量发布已经落地**，时间线是最近两周。

更关键的是：这 33k 不是「单臂抓放」的同质数据。它是**同步双臂、同步四路相机、同步夹爪开度**的数据——左手和右手在同一时间戳上，天然可以算相对位姿、速度相关、相位滞后、支撑/操作角色。这是本轮「演示数据」灵感词的技术入口：**演示不只是用来模仿动作，更是用来编译协同程序**。

### 0.5 「协同控制」不是口号：5 个任务的逐帧统计给出五种不同模式

我对 5 个任务的 `data/chunk-000/file-000.parquet` 做了逐帧统计（[S6]；每文件 269–719 条 episode，不是全量，但足以看结构）。定义：

- **grasp**：`gripper < episode_p90 − 0.6`（夹爪闭合到接近物体宽度）；
- **support-actor**：一手 grasp 且 EE 速度 < **0.008 m/s**，另一手 grasp 且 EE 速度 > **0.03 m/s**；
- **speed corr**：左右 EE 线速度在 ±30 帧内取最大 Pearson 相关；
- **hand-dominance switches**：左右速度差（0.5s 滑动平均）在双手都 grasp 时的符号切换次数，|Δv|>0.005 m/s 才计数；
- **regrasp**：至少出现一次 close→open→close 的 episode 比例。

结果如下（episode 均值）：

| 任务 | episodes | 平均长度 | both-grasp | support-actor | speed corr | lag | switches | 判读 |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| HangCup | 719 | 6.1s | **0.3%** | **0.0%** | **+0.59** | −0.5 帧 | **0.01** | 单臂（右手） |
| StackBowls | 412 | 10.3s | 14.9% | 1.9% | +0.06 | +2.4 帧 | 0.42 | 顺序双手/交替 |
| FoldTowel | 142 | 29.3s | 32.5% | 2.4% | +0.26 | 0 | **7.11** | 紧协同 + 高频重抓/折叠 |
| ZipUp | 369 | 11.9s | **46.4%** | **12.4%** | −0.07 | −1.4 帧 | **1.13** | 支撑-操作交替（弱反相） |
| PlugCharger | 269 | 16.2s | **41.6%** | 7.9% | **+0.29** | −0.5 帧 | 0.14 | 同相联合搬运 + 非对称力/精握 |

夹爪与重抓细节：

| 任务 | regrasp L/R | aperture L/R | grasp 时长 L/R | 备注 |
|---|---:|---:|---:|---|
| HangCup | 0 / 12.8% | 2.50 / **1.02** | 0.04s / **3.28s** | 左手几乎不参与，2.50 是极短 grasp 的噪声 |
| StackBowls | 21.6% / **49.8%** | 1.54 / 1.73 | 3.22s / 3.90s | 右手重抓更多，像“交替叠放” |
| FoldTowel | **93.0% / 99.3%** | 1.21 / 0.87 | 6.90s / 5.07s | 两只手都反复抓/放，折叠需要重抓 |
| ZipUp | **75.6% / 72.4%** | 0.70 / 0.75 | 3.71s / 4.88s | 左手高频重抓，右手拉链 |
| PlugCharger | 50.6% / 11.5% | **3.30 / 1.80** | 7.63s / 6.71s | 左手大力握插排，右手精细握插头 |

这组数字说明：**32 个任务不能用一个“双手策略”通吃**。HangCup 近似单臂；StackBowls 是顺序交替；ZipUp 是支撑-操作交替；PlugCharger 是同相搬运 + 非对称孔径；FoldTowel 是紧协同 + 重抓。把它们都塞进一个无条件的 VLA，模型会学到“平均动作”，而不是“在正确相位切换正确角色”。这就是 DUET 的第一个切入点。

### 0.6 「灵巧手」的正确翻译：孔径、力型、环境接触与重抓

Dex1 只有 1-DOF，但有三个可观测/可控的量：

1. **孔径**：`gripper` 开度在 0–5.5 之间连续变化；数据里 PlugCharger 左 3.30 / 右 1.80，说明同一任务里存在**大力握（power grasp）**与**精细握（precision grasp）**两种模式。夹爪不是二值开合，孔径本身是“虚拟手指”的配置参数。
2. **力型**：5–120N 可调，但 API 没有力传感器；只能用“孔径命令 vs 实际孔径”的差、EE 跟踪误差、腕部视觉滑移做**力代理**。这不是完美的力控，但足以支撑“先轻后重、滑移再夹紧”的策略。
3. **环境接触**：桌面、架子、盒子、另一只手都可以当夹具。比如插网线时，支撑手握住网口，操作手把网线插进去；叠碗时，支撑手扶住碗1，操作手放碗2。**没有手指，就把环境变成手指**。

因此本轮把「灵巧手」翻译成 **VDX（Virtual Dexterity）**：孔径条件抓取（ACG）+ 力型选择 + 环境支撑 + 重抓/手递手。它不是“仿五指手”，而是“在 1-DOF 约束下把可用的自由度用到极致”。

### 0.7 「演示数据」的正确用法：从模仿到协同挖掘 + 官方剧本回放

33k 演示至少有三层价值：

1. **动作先验**：常规 imitation / flow matching；
2. **协同结构**：逐帧角色、相位、相对位姿、孔径、重抓，可编译成 BCC 的约束图；
3. **扰动剧本**：官方 `info.json` 的 `human_1_note` / `human_4_note` 已经给出人类干扰的逐任务描述（[S4]）。

官方备注的例子（原文）：

- T27 StackBowls：human_1「把粉色碗向下移动」；human_4「叠了第二个之后拿下第二个」；
- T19 ZipUp：human_1「把包向左边移动」；human_4「拉上拉链之后拉开」；
- T14 OpenPillBottle：human_1「拧开盖子之后拧动回来」；
- T17 OrganizeStationery：human_4「笔盒合上之后手动打开」；
- T10 PlugCharger：human_1「抓插头前进行移动」；human_4「将插头拔起」；
- T26 PlugInEthernet：human_1「把网线移开」；human_4「把插口移开」；
- T24 ConveyorSorting：human_1「可乐快到了然后放回传送带起点」；human_4「薯片快到了然后放回传送带起点」；
- T31 PencilCase / T32 SyringeWaterTransfer 的 human 备注为空。

这些备注有两个共同点：**绝大多数是对支撑物/目标物做一次平移，或对已完成动作做一次撤销**。这正好是协同策略最脆弱的地方：支撑物被移走、目标物被挪开、拉链被拉开、盖子被拧回。NRB 从“自造扰动”升级为“官方剧本忠实回放”，CPE 也有了明确的扰动语法。

### 0.8 评测算术与接口边界

官方手册：每任务 **10 次独立运行**，5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰）**各出现 2 次**，共 **320 trials**；通才赛道单模型跑全部 32 任务；排名先成功率、再步骤分、再提交时间（[S1][S2]）。由此：

| 量 | 数值 | 含义 |
|---|---:|---|
| 总 trials | 32 × 10 = **320** | 成功率样本量 |
| 单任务权重 | 10/320 = **3.125pp** | 一个任务 0%→100% 的总分增益 |
| 单泛化轴权重 | 64/320 = **20%** | 某一轴全线失败最多损失 20pp |
| 总体成功率 SE（p≈0.3） | **≈2.56pp** | +3pp 约 1.2 SE，统计上不稳 |
| 一个 catastrophic zero | **−3.125pp** | 5 个任务全零直接 −15.6pp |

所以本轮预算逻辑是：**先消除 catastrophic zeros，再攻跨轴协同，最后才做步骤分微调**。协同恰好同时作用于三者：支撑手不丢（跨轴）、拉链/插头/网口能闭环（消除零）、human 撤销后能恢复（人为轴）。

接口边界（[S7]）：四路 RGB、双臂 joint/EE、夹爪开度、`lower_body`、`observation.language` 单字符串；`control_space` 二选一（joint / ee）；`obs_chunk_size`、`action_chunk_size`、`token`；`reset()` 每 episode 一次。**没有力/力矩观测**；`action.gripper_controls[4]` 语义与 state 不直接对齐，不能当可靠力反馈。`action.pivot[7]` 在我的 5 任务抽样里：`vx/vy/angle_z` 几乎全为 0，只有 FoldTowel 的 `angle_z` 到 0.8 rad、`height` 在 0.68–0.74 之间变化；StackBowls 的 `vx` 最大 0.032（[S6]）。结论：**UniBot 的协同主要是上半身协同，底盘/步态不是主线**；不要把手脚协调写成主方案。

## 1. 三个灵感词，各自钉到官方事实上

### 1.1 协同控制：官方第三支柱，而且是最被低估的跨轴杠杆

`challenges.html` 把 32 个任务概括为 **grasping, placement and bimanual coordination**（[S3]）。这不是宣传语：0.5 的统计已经证明不同任务的双手结构差异巨大。协同之所以是“铰链”，有三个原因：

1. **它是终局动作的前置条件**：插头要插进插排，必须有一只手按住插排；拉链要拉上，必须有一只手把包摆正/压住；碗要叠上去，必须有一只手扶住下面的碗。终局是 success 的闸门，协同是终局的前置。
2. **它跨全部 5 个泛化轴**：位置轴移动支撑物/目标物；干扰物轴遮挡支撑手；背景轴改变视觉锚点；未见物品轴改变物体几何/孔径；人为轴直接撤销支撑或目标。协同策略在五个轴上都被考。
3. **它能把“部分分”变成“成功率”**：一个任务如果只会抓不会插，步骤分可能拿到 60，但 success=0；协同闭环把最后 40 分变成 1 个 success，排名收益远大于步骤分微调。

### 1.2 灵巧手：1-DOF 不是缺陷，而是把灵巧转移到“手外”

如果把灵巧定义成“手指自由度”，UniBot 一开始就输了；但如果把灵巧定义成“在任务约束下配置接触”，1-DOF 夹爪仍有很大的设计空间：

- **孔径**：同一任务里 power vs precision（PlugCharger 3.30 vs 1.80）；
- **力型**：先轻夹对齐，再重夹固定；滑移时二次夹紧；
- **接触点**：夹爪指尖、夹爪侧面、桌面、架子、另一只手；
- **重抓**：FoldTowel 双手重抓率 93.0%/99.3%，ZipUp 左手 75.6%；
- **手递手**：两只手同时抓住物体，再释放一只，实现“换手”；
- **非抓取操作**：推、拨、压、翻、拉，不一定要抓住。

这六条构成 VDX。它不承诺“多指手内操作”，只承诺“在 1-DOF 下把可用接触用到极致”。这是诚实且可验证的边界。

### 1.3 演示数据：33k 同步轨迹是“协同程序”的语料，不是“动作克隆”的燃料

常规 VLA 训练把演示当 `(observation, action)` 对，最多做数据增强。DUET 把每条演示同时看成：

```text
演示 τ = 动作序列 + 双手角色序列 + 相位序列 + 相对位姿约束 + 孔径剖面 + 重抓/手递手事件
```

于是同一条演示可以产出五类监督：

1. 动作（flow matching / diffusion）；
2. 角色（idle / support / actor / handover）；
3. 相位（approach / grasp / transport / insert / release / verify）；
4. 几何（相对位姿、接近向量、释放位姿、孔径目标）；
5. 事件（重抓、滑移、支撑丢失、human undo）。

这五类监督让 33k 数据从“模仿”升级为“可审计的协同程序”。如果官方允许使用 Unitree 更广的 `UnifoLM_G1_Dex1_Dataset`（约 72 任务，含 Connect_The_Network_Port、Open_Bottle_Cap、Unzip、Cover_The_Tool_Box、Pour_Drink、Store_Coins 等，[S23]），还可以做同构跨任务预训练；但这是合规模块，默认 OFF，必须先确认 external data 政策。

## 2. 新主判断：从 PILOT 到 DUET

### 2.1 一句话

**PILOT 把放置当闸门，DUET 把协同当铰链。** 放置仍然是终局闸门，但协同决定了模型能不能把物体送到闸门前、能不能在 human 撤销后重新组织双手、能不能在 1-DOF 夹爪下把接触配置对。

### 2.2 PILOT 与 DUET 的分层关系

| 层 | PILOT（第 7 轮） | DUET（本轮） | 为什么保留/升级 |
|---|---|---|---|
| 终局 | SSG + PGL + OPT + SVL | **保留为 terminal layer** | 放置仍是 success 闸门；SSG 现在用于相位诊断 |
| 协同 | 无显式层 | **BCC + CSR + CCPL** | 官方第三支柱；跨 5 轴 |
| 灵巧 | 夹爪开合 | **VDX + ACG** | 1-DOF 的补偿；孔径/力型/环境 |
| 数据 | 全量模仿 + 场景增强 | **CRM + CPE** | 协同富集 + 官方剧本 |
| 模型 | GPR-VLA / WLA | **MCAE** | 模式/角色/相位/孔径条件 |
| 恢复 | NRB 自造扰动 | **NRB 官方剧本 + CSR** | human 轴 20% 权重 |
| 评测 | DebugLoop + L2L | **保留，加协同指标** | 不计分调试槽是真机回路 |

### 2.3 DUET 明确不做什么

为了避免把方案写成“万能清单”，本轮先划掉六件事：

1. **不做多指灵巧手**：硬件是 1-DOF，任何“手指级”主张都是伪创新；
2. **不做全屋/全身数字孪生**：33k 真实数据 + 官方备注足够，孪生成本高、sim-to-real 风险大；
3. **不做步态/足端规划**：`action.pivot` 抽样显示底盘基本固定；协同是上半身问题；
4. **不做每任务 LoRA/专家**：规则要求单模型，per-task 适配器既违规又不可扩展；
5. **不做运行时 MPC/RL**：180s 时限 + API 黑盒，在线优化不现实；监督层用确定性规则；
6. **不做无力传感器的“精确力控”**：只做孔径/跟踪误差/视觉滑移的力代理。

### 2.4 预算分配（按研究火力）

| 方向 | 占比 | 理由 |
|---|---:|---|
| 协同编译 + 监督 + 数据 | **40%** | 本轮主创新；跨轴；官方第三支柱 |
| 终局放置/验证 | 25% | success 闸门；PILOT 已有积累 |
| 恢复/扰动 | 20% | human 轴 20% 权重；官方备注可直接用 |
| 部署/接口/合规 | 15% | 单模型、远程 API、180s |

### 4.2 BCC：把演示编译成协同程序

BCC 的输入是演示 `τ = {(o_t, a_t)}_{t=1}^T` 和任务 `k` 的评分步骤 `S_k`；输出是四类 token 和一张约束图。

```text
算法 BCC
输入：演示 τ，任务 k，评分步骤 S_k，阈值 θ
输出：每帧 (m_t, r_t, p_t, a*_t, c_t)

1. 逐帧特征
   gL_t, gR_t = 左右夹爪开度
   vL_t, vR_t = 左右 EE 线速度
   d_t = ||pL_t − pR_t||
   graspL_t = 1[gL_t < p90(gL) − 0.6]
   graspR_t = 1[gR_t < p90(gR) − 0.6]

2. 相位分割
   用夹爪 close/open 事件 + EE 速度谷值 + S_k 的步骤边界
   把 episode 切成 approach / grasp / transport / insert / release / verify
   允许一个步骤内多个子相位

3. 角色标注
   若 graspL_t 且 graspR_t：
      若 ||vL_t|| < 0.008 且 ||vR_t|| > 0.03 → rL=support, rR=actor
      若 ||vR_t|| < 0.008 且 ||vL_t|| > 0.03 → rR=support, rL=actor
      若两者都 > 0.03 → 同相 actor（I）
   若仅一手 grasp：
      该手 actor，另一手 idle
   handover：双手同时 grasp，随后一手 open 且另一手保持 grasp
   用 Viterbi 平滑，转移先验由训练集统计给出

4. 模式软分类
   对每条 episode 计算：
     both = mean(graspL & graspR)
     sa   = mean(support-actor)
     corr = max_lag corr(||vL||, ||vR||)
     lag  = argmax_lag corr
     sw   = support/actor 切换次数
     rg   = 重抓次数
   m = softmax(MLP([both, sa, corr, lag, sw, rg, aperture 差]))
   输出 U/S/A/I/F 分布，不硬切

5. 约束图
   节点：左手、右手、物体1..n、夹具/桌面/架子
   边：
     support(left, object) / support(right, object)
     relative_pose(left, right, Δp*, ΔR*)
     phase_lag(left, right, lag*)
     aperture(left, a*L) / aperture(right, a*R)
     approach_vector(object, v*)
   约束图按相位激活，不是全程固定

6. 输出 token
   m_t（mode 分布）、r_t（role）、p_t（phase）、a*_t（孔径目标）、
   c_t（激活的约束边），送到 MCAE 和 CSR
```

BCC 与同期协同 VLA 的区别：Co-VLA、Coordi-π、TwinVLA 等把协同作为**策略学习目标/表示学习**（[S13][S14][S15]）；DUET 把协同先编译成**可审计的角色/相位/约束**，再让策略学习执行。前者是 end-to-end，后者是 `compile → execute → supervise`。在 1-DOF、无力的 UniBot 上，后者的可解释性和可调试性更重要。

### 4.3 VDX：虚拟灵巧

VDX 由四个策略组成：

1. **ACG 孔径条件抓取**：给定物体宽度 `w` 和抓取类型 `q ∈ {power, precision, pinch}`，目标孔径 `a* = w + clearance(q)`；闭合时监控 `g_t − g_{t−1}`，当孔径变化率骤降（接触代理）或达到 `a*` 时停止；薄物体允许 over-close 到 0.05。
2. **力型选择**：power 用于插排/盒子/碗（目标 3.0–3.8），precision 用于插头/网线/钥匙（目标 1.2–1.6）；先轻夹对齐，再重夹固定；滑移时二次夹紧。
3. **环境支撑**：桌面/架子/盒子/另一只手作为 fixture；支持“压住再拉”“顶住再拧”“扶住再插”；不追求把物体完全抬离桌面。
4. **重抓/手递手**：当滑移、对齐误差、相位回退时触发；重抓点由腕部近场图像 + 当前物体位姿选择；手递手要求双手同时 grasp，释放一只手后另一只手保持相对位姿。

VDX 的边界：**不声称 finger-level 操作，不声称精确力控**；它只利用 1-DOF 夹爪可观测的孔径、速度和接触代理。

### 4.4 CRM：协同富集演示挖掘

CRM 不是“再采样一遍”，而是按协同结构分层：

- 对每条 episode 计算 BCC 特征 `[both, sa, corr, lag, sw, rg, aperture 差]`；
- 按主模式分层，保证 U/S/A/I/F 在每个 batch 中都有代表；
- 对高协同 episode 加权：`w_i = (1/freq(m_i))^α · (1 + β·coordination_score_i)`，`α=0.3`、`β=0.5`，上限 3×；
- 对 U 任务不降权，只做“角色 token dropout”，防止模型只会单臂；
- 语言侧覆盖 5 条复述（32×5=160 条，[S5]），并用任务名/步骤描述做 paraphrases。

关键点：**不是把 ZipUp 复制 3 倍，而是让每个 batch 都看到“支撑-操作”的结构**。否则模型会记住 ZipUp 的表面动作，而学不到可迁移的协同。

### 4.5 CSR：运行时协同监督

CSR 是确定性规则层，不学习，10–20Hz 运行，输出“继续/暂停/重抓/重试/退避”五类门控。

监控量：

| 监控 | 计算 | 触发 | 动作 |
|---|---|---|---|
| support drift | 支撑手 EE 位移 > 5mm 或支撑物视觉位移 > 8mm | 支撑丢失 | 暂停 actor，re-anchor |
| aperture slip | 实际孔径 − 目标孔径 > 0.5 且 EE 静止 | 滑移 | 二次夹紧/重抓 |
| phase stall | 相位进度 2s 不前进 | 卡住 | 退回上一相位/重试 |
| insertion fail | 插入尝试 3 次失败 | 对齐失败 | 螺旋搜索/换接近向量 |
| human proximity | 腕部/头部视觉检测到人手进入工作区 | 人为干扰 | 减速/后退/等待 |
| collision proxy | EE 与已知障碍距离 < 2cm | 碰撞风险 | 限速/绕行 |
| timeout | episode 剩余时间 < 15s | 超时风险 | 放弃长尾，保当前步骤 |

CSR 的价值在于：**它把“协同”从模型内隐变量变成运行时可见的状态**。模型可以错，但监督层可以在支撑丢失时停下来，而不是继续把插头往错误方向推。

### 4.6 CPE：协同扰动引擎

CPE 的扰动语法直接来自官方 human 备注：

```text
event := translate(object, direction, magnitude)
       | remove(object)
       | undo(step)
       | delay(arm, duration)
       | swap_roles(left, right)
       | perturb_aperture(arm, delta)
       | occlude(camera, region, duration)
```

实现分三层：

1. **离线回放**：在演示数据上做对象平移/撤销/延迟，生成协同恢复样本；
2. **仿真扰动**：如果有轻量桌面仿真，注入同样的事件，做闭环；
3. **真机调试槽**：在 T19/T10/T26/T27/T16 上按官方备注复现，验证 CSR。

CPE 与 NRB 的分工：CPE 生成“扰动”，NRB 存“恢复脚本”；两者共用事件语法。

### 4.7 MCAE：模式/角色/相位/孔径条件动作专家

MCAE 是单模型、单 checkpoint 的动作专家：

- **底座**：WLA-1.0-Base 6B（[S12]）或 GR00T N1.5 / π0.5 级别的 VLA；LoRA 微调，保持单模型；
- **输入**：4 路 RGB、双臂 proprio、夹爪开度、language、BCC token（mode soft label、role、phase、aperture target、relative pose）；
- **主干**：共享视觉-语言 trunk + 双臂共享动作 trunk + 左右臂 residual heads；
- **输出**：joint 或 EE action chunk（50 步）、gripper 目标、可选相对位姿；
- **损失**：

```text
L = L_flow(action | obs, language, tokens)
  + λ1 L_CE(role)
  + λ2 L_CE(mode)
  + λ3 L1(aperture_target)
  + λ4 L1(relative_pose)
  + λ5 L_CE(phase_progress)
```

- **训练**：33k episodes，10–20k steps，bf16，1–2 张 24–80GB GPU；50-step chunk；推理 0.3–0.5s（参考公开 6B LoRA 基线，[S24]）；
- **单模型合规**：任务条件只通过 language / task embedding / BCC token，不训练 per-task 权重。

MCAE 与普通 VLA 的差异：普通 VLA 只学 `p(a|o,l)`；MCAE 学 `p(a|o,l,m,r,p,a*,c)`，把协同结构作为条件而不是隐变量。这样同一个 checkpoint 可以在 HangCup（U）和 ZipUp（A）之间切换角色策略，而不是被平均掉。

### 4.8 ACG：孔径条件抓取

ACG 是 VDX 的低层控制器，也是 MCAE 的辅助头：

- 预测目标孔径 `a*` 和抓取类型 `q`；
- 闭合控制：`g_{t+1} = g_t − η`，直到接触代理或 `a*`；
- 滑移监控：`|g_t − a*| > δ` 且 EE 速度 < 0.01 → 二次夹紧；
- 重抓：滑移连续 2 帧或视觉滑移 > 阈值 → 释放、抬高 2cm、重新对准；
- 对薄物体（网线、拉链头、纸）允许 over-close；对易碎物（药瓶、耳机）限制最大夹持力代理。

### 4.9 CCPL：跨任务协同原语库

CCPL 是 8 个可复用原语：

| 原语 | 前置 | 参数 | 后置 | 典型任务 |
|---|---|---|---|---|
| anchor | 支撑物可见 | 接触点、力型 | 支撑手稳定 | T10/T19/T26 |
| brace | 物体可压 | 压点、方向 | 物体不滑 | T16/T31 |
| pull | 一手固定 | 方向、距离 | 目标位移 | T05/T30 |
| twist | 一手固定 | 轴、角度 | 盖子/钥匙转动 | T12/T14 |
| insert | 两物对齐 | 接近向量、深度 | 插入到位 | T10/T26/T32 |
| handover | 双手可抓 | 释放手、时机 | 换手完成 | T18/T28 |
| fold | 柔性物 | 折线、压点 | 折叠完成 | T16/T31 |
| zip | 拉链头可见 | 方向、张力 | 拉链闭合 | T19/T23/T31 |

CCPL 不是“技能库”式的硬编码执行器，而是 BCC 约束图的**可调用子图**；MCAE 仍输出低层动作，CCPL 只提供参数和相位先验。

### 4.10 与 PILOT 终局层的集成

DUET 不推翻 PILOT，而是把 PILOT 放在下游：

- **SSG**：32 任务评分步骤图；现在同时用于相位标签和恢复触发；
- **PGL**：放置目标阶梯（slot → 2D anchor → 6D pose）；
- **OPT**：K 条演示的容器系释放位姿中位数 + 离散度；
- **SVL**：settle-verify 闭环；插入/放置后等待 0.3–0.5s，再判定；
- **NRB**：官方 human 备注回放 + 恢复脚本；
- **L2L**：本地离线指标 → 真机调试槽 → 计分跑的校准协议；
- **DebugLoop**：不计分单任务调试（[S8]），用于 T19/T10/T26/T27/T16 的 A/B。

集成顺序：

```text
BCC 预测 mode/role/phase
  → MCAE 生成动作
  → CSR 门控
  → PGL/OPT 提供终局目标
  → SVL 验证
  → 失败则 NRB/CCPL 恢复
```

## 5. 创新点清单（保留/升级/新增/修剪）

### 5.1 新增核心（本轮主押注）

#### I14 BCC：双手协同编译器

- **动机**：33k 同步演示里有角色/相位/约束，但普通 VLA 只学动作，学不到“什么时候谁支撑、谁操作”。
- **差异**：Co-VLA/Coordi-π/TwinVLA 把协同作为端到端学习目标（[S13][S14][S15]）；BCC 把协同显式编译成可审计的图，再条件化策略。
- **可行性**：数据有左右手、夹爪、EE、时间戳；5 任务统计已证明模式可分；无需额外标注。
- **资源**：离线 CPU + 1 张 GPU 做分类器；2 人周。
- **步骤**：特征 → 相位 → 角色 → 模式 → 约束图 → token。
- **风险**：模式覆盖不全；用 soft label + 人工抽检 50 条/任务缓解。

#### I15 VDX：1-DOF 虚拟灵巧

- **动机**：Dex1 不是灵巧手；必须用孔径、力型、环境、重抓补偿。
- **差异**：不追求多指手内操作；把“接触配置”作为可学习/可控制的变量。
- **可行性**：孔径连续可观测；PlugCharger 已显示 3.30 vs 1.80 的非对称；FoldTowel/ZipUp 重抓率高。
- **资源**：ACG 头 + 规则控制器；1 人周。
- **步骤**：孔径目标 → 闭合控制 → 滑移监控 → 重抓/手递手。
- **风险**：无力传感器；只做代理，不宣称精确力控。

#### I16 CRM：协同富集演示挖掘

- **动机**：33k 数据里 U 任务多、A/F 任务少；均匀采样会让模型偏向单臂。
- **差异**：按协同模式分层 + 高协同加权 + 角色 token dropout；不是简单复制。
- **可行性**：BCC 特征可离线计算；采样器实现简单。
- **资源**：离线特征 + 训练 sampler；0.5 人周。
- **步骤**：特征 → 分层 → 权重 → batch 约束。
- **风险**：加权过度会过拟合 A/F；用上限 3× 和验证集监控。

#### I17 CSR：运行时协同监督

- **动机**：端到端模型在支撑丢失/滑移/人为干扰时不会停下来重新组织。
- **差异**：确定性规则层，不改模型权重；把协同状态显式化。
- **可行性**：EE/夹爪/腕部图像都可观测；10–20Hz 足够。
- **资源**：CPU 规则引擎；1 人周。
- **步骤**：监控量 → 触发器 → 门控动作 → 安全边界。
- **风险**：规则保守会拖慢；用“只在中高置信度触发”+ 超时回退。

#### I18 CPE：协同扰动引擎

- **动机**：human 轴 20% 权重；官方备注给出了逐任务剧本。
- **差异**：不是通用图像增强，而是“支撑物平移/撤销/延迟/角色交换”的结构化扰动。
- **可行性**：官方备注可解析；离线回放不需要仿真。
- **资源**：事件解析器 + 数据管线；1 人周。
- **步骤**：解析备注 → 事件语法 → 离线/仿真/真机三层。
- **风险**：备注不完整（T31/T32 为空）；用通用扰动补足。

#### I19 MCAE：模式/角色/相位/孔径条件动作专家

- **动机**：单模型要同时覆盖 U/S/A/I/F，需要条件化而不是平均化。
- **差异**：普通 VLA 只条件化语言/图像；MCAE 额外条件化协同 token。
- **可行性**：WLA/GR00T/π0.5 底座 + LoRA；33k 数据足够。
- **资源**：1–2 张 GPU；2 人周。
- **步骤**：token 注入 → 双臂 residual → 辅助损失 → 单 checkpoint。
- **风险**：token 泄漏/过拟合；用 token dropout 和 held-out 任务验证。

#### I20 ACG：孔径条件抓取

- **动机**：夹爪不是二值；孔径决定力型、滑移和插入成功率。
- **差异**：从“open/close”升级为“目标孔径剖面 + 接触代理 + 二次夹紧”。
- **可行性**：数据有孔径；5 任务已显示非对称孔径。
- **资源**：辅助头 + 规则；0.5 人周。
- **步骤**：孔径预测 → 闭合控制 → 滑移监控。
- **风险**：孔径噪声；用 episode 内归一化和滑移滤波。

#### I21 CCPL：跨任务协同原语库

- **动机**：anchor/brace/pull/twist/insert/handover/fold/zip 在 32 任务中反复出现。
- **差异**：不是 per-task 技能，而是 BCC 约束图的可调用子图。
- **可行性**：评分步骤/描述已给出原语线索；数据可挖参数。
- **资源**：规则 + 参数回归；1 人周。
- **步骤**：定义原语 → 从演示挖参数 → 接 BCC/CSR。
- **风险**：原语边界模糊；用软激活，不硬编码执行。

## 6. 实验与 go/no-go

### 6.1 离线

| 指标 | 目标 | 数据 |
|---|---|---|
| 模式分类 macro-F1 | > 0.75 | 5 任务人工标签 + 32 任务弱标签 |
| 角色标注 F1 | > 0.80 | 50 条/任务人工抽检 |
| 孔径目标 MAE | < 0.3 | 演示孔径 |
| 相对位姿 MAE | < 1cm / 5° | 演示 EE |
| 相位进度误差 | < 1 相位 | SSG 对齐 |

### 6.2 真机调试槽（不计分）

优先级：**T19 ZipUp（A）→ T10 PlugCharger（I）→ T26 PlugInEthernet（A/I）→ T27 StackBowls（S）→ T16 FoldTowel（F）**。理由：覆盖 A/I/S/F 四种模式，且都是终局插入/闭合/堆叠，success 信号清晰。

每个任务 A/B：baseline（PILOT/WLA）vs DUET（BCC+MCAE+CSR）。每轮 10–20 次，记录 success、step、支撑丢失、重抓、完成时间。

### 6.3 消融

| 消融 | 验证什么 |
|---|---|
| 去掉 BCC token | 协同条件是否真的有用 |
| 去掉 role token | 角色显式化是否必要 |
| 去掉 aperture token | 孔径条件是否必要 |
| 去掉 CSR | 运行时监督是否必要 |
| 去掉 CRM | 协同分层采样是否必要 |
| 去掉 CPE | 扰动数据是否必要 |
| 去掉 PGL/OPT/SVL | 终局层是否仍必要 |
| 只用 U 数据 | 模型是否退化成单臂 |

### 6.4 go/no-go

- **Go**：在 T19/T10/T26 上，support/actor 步骤分 **+10pp**，终局 success **+5pp**，U 任务（HangCup）无回归；CSR 延迟 < 100ms；单模型审计通过。
- **No-go**：协同 token 无增益，或 CSR 触发过频导致完成时间 > 1.5×；则回退到 PILOT 终局层 + 轻量 ACG，不强行上 DUET。
- **统计**：320 trials，p≈0.3 时 SE≈2.56pp；用配对任务 bootstrap，不用单次总分下结论。

### 6.5 什么会推翻本轮判断

- 若 32 任务协同统计显示 **>70% 的任务 both-grasp <5% 且 support-actor <1%**，说明 UniBot 主要是单臂 benchmark，协同不是铰链 → 退回 PILOT + 终局层，不强行上 DUET。
- 若 T19/T10/T26 调试槽上 BCC token 相对 baseline 的 support/actor 步骤分增益 **<3pp**，说明显式协同条件无效 → 把 BCC 降级为诊断工具，主攻终局放置/恢复。
- 若真实榜首 **>50%** 且失败主要是抓取/感知而非协同，说明瓶颈不在协同 → 重新分配预算到感知/抓取。
- 若 CSR 触发导致完成时间 **>1.5×** 或 success 下降，说明监督层过度保守 → 只保留 support drift / timeout 两条。

# DUET 技术报告：双手协同编译器、虚拟灵巧与协同扰动数据

> 版本：2026-10-25（UTC）。范围：UniBot 世界挑战赛通才赛道（G1 + Dex1，32 任务，单模型，远程真机 API）。本报告是「想法区」DUET 方案的工程化展开，包含事实基线、问题形式化、协同模式、架构、数据引擎、训练配方、运行时监督、实验协议、8 周计划、风险与来源。所有外部事实标注来源；占位数据明确标注，不作为真实排名依据。

## 0. 执行摘要

**问题**：官方把「抓取、放置、双手协调」并列为三大能力；但 Dex1 是 1-DOF 平行夹爪，不是灵巧手。多数公开 VLA 方案把 32 任务当同质数据做端到端模仿，没有显式建模「谁支撑、谁操作、何时换角色、夹爪开多大、支撑物被移走怎么办」。

**判断**：在 UniBot 里，灵巧性不在手指，而在**双手角色、相位、夹爪孔径、环境夹具与重抓**；33k 同步演示是协同语料；官方 human 备注是协同扰动剧本。PILOT 把放置当闸门是对的，但协同是让闸门可达的铰链。

**方案**：DUET = BCC（协同编译器）+ VDX（虚拟灵巧）+ CRM（协同富集演示挖掘）+ CSR（运行时协同监督）+ CPE（协同扰动引擎）+ MCAE（模式/角色/相位/孔径条件动作专家）+ ACG（孔径条件抓取）+ CCPL（跨任务协同原语库）。PILOT 的 SSG/PGL/OPT/SVL 保留为终局层，NRB 升级为官方剧本回放。

**预期**：在协同密集任务（T19 ZipUp、T10 PlugCharger、T26 PlugInEthernet、T27 StackBowls、T16 FoldTowel）上，support/actor 步骤分 +10pp、终局 success +5pp；U 任务（HangCup）无回归；单模型、单 checkpoint、无 per-task 权重。

**不做什么**：不做多指灵巧手、不做全屋数字孪生、不做步态/足端规划、不做每任务 LoRA、不做运行时 MPC/RL、不无力传感器却宣称精确力控。

## 1. 事实基线

### 1.1 赛事与评分

官方中文手册（[S1]，英文 [S2] 同义）：

- 32 个桌面任务；通才赛道单模型跑全部 32 任务；
- 每任务 **10 次独立运行**，5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰）**各出现 2 次**；
- 总 trials = 32 × 10 = **320**；
- 榜单按 **总平均成功率** 排序；成功率相同按 **总平均步骤分**；仍相同按 **提交时间**；
- 允许 World Model、VLA 等任意架构；选手自部署，官方只远程调 API；
- 另有**不计分单任务调试**，需预约 + 管理员确认（[S8]）。

评测算术：

| 量 | 数值 | 含义 |
|---|---:|---|
| 总 trials | 320 | 成功率样本量 |
| 单任务权重 | 3.125pp | 一个任务 0%→100% 的总分增益 |
| 单泛化轴权重 | 20% | 64/320 |
| 总体成功率 SE（p≈0.3） | ≈2.56pp | +3pp 约 1.2 SE |
| 一个 catastrophic zero | −3.125pp | 5 个任务全零 −15.6pp |

结论：**先消除 catastrophic zeros，再攻跨轴协同，最后做步骤分微调**。协同同时作用于三者：支撑手不丢（跨轴）、拉链/插头/网口闭环（消除零）、human 撤销后恢复（人为轴）。

### 1.5 协同统计（file-000）

对 5 个任务的 `data/chunk-000/file-000.parquet` 做逐帧统计。定义：

```text
g_open = 4.5（数据开度）
grasp c_t^h = 1[g_t^h < 3.8]        # g_open − 0.7；稳健性检查用 per-episode p90−0.6
both b_t = c_t^L · c_t^R
support-actor s_t = 1[b_t · ||v_t^L||<0.008 · ||v_t^R||>0.03]
                  + 1[b_t · ||v_t^R||<0.008 · ||v_t^L||>0.03]
speed corr ρ* = max_{|ℓ|≤30} corr(||v_{t+ℓ}^L||, ||v_t^R||)
dominance switches = sign changes of 15-frame moving average(||v^L||−||v^R||)
                     while b_t, only when |Δ|>0.005 m/s
regrasp = episode has close→open(≥2 frames)→close
aperture = mean g_t^h over c_t^h frames
grasp duration = mean length of continuous c_t^h runs
```

结果：

| 任务 | episodes | 长度 | both | support-actor | ρ* | lag | switches | 判读 |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| HangCup | 719 | 6.1s | 0.3% | 0.0% | +0.59 | −0.5 | 0.01 | U |
| StackBowls | 412 | 10.3s | 14.9% | 1.9% | +0.06 | +2.4 | 0.42 | S |
| FoldTowel | 142 | 29.3s | 32.5% | 2.4% | +0.26 | 0.0 | 7.11 | F |
| ZipUp | 369 | 11.9s | 46.4% | 12.4% | −0.07 | −1.4 | 1.13 | A/F |
| PlugCharger | 269 | 16.2s | 41.6% | 7.9% | +0.29 | −0.5 | 0.14 | I |

夹爪与重抓：

| 任务 | regrasp L/R | aperture L/R | grasp 时长 L/R | 备注 |
|---|---:|---:|---:|---|
| HangCup | 0 / 12.8% | 2.50 / 1.02 | 0.04s / 3.28s | 左手几乎不参与；2.50 是极短 grasp 噪声 |
| StackBowls | 21.6% / 49.8% | 1.54 / 1.73 | 3.22s / 3.90s | 右手重抓更多，交替叠放 |
| FoldTowel | 93.0% / 99.3% | 1.21 / 0.87 | 6.90s / 5.07s | 双手反复抓/放，折叠重抓 |
| ZipUp | 75.6% / 72.4% | 0.70 / 0.75 | 3.71s / 4.88s | 左手高频重抓，右手拉链 |
| PlugCharger | 50.6% / 11.5% | 3.30 / 1.80 | 7.63s / 6.71s | 左手大力握插排，右手精细握插头 |

**限制**：只分析了 `file-000`，不是全量；阈值用 5 任务校准；`support-actor` 对速度阈值敏感；`speed corr` 对噪声和相位滞后敏感。结论用于**分层和假设**，不用于最终统计。全量 32 任务应重跑并做人工抽检。

### 1.6 接口与边界

提交仓库 README（[S7]）：

- 观测：4 路 RGB、双臂 joint/EE、夹爪开度、`lower_body`、`observation.language` 单字符串；
- 动作：`control_space` 二选一（joint / ee）；
- 可选：`data_keys` / `obs_chunk_size` / `action_chunk_size` / `token`；旧版镜像还有 `obs_delta_indices` / `image_resize`，提交前需核对当前仓库版本；
- `reset()` 每 episode 一次；
- **没有力/力矩观测**；`action.gripper_controls[4]` 与 state 不直接对齐，不能当可靠力反馈；
- `action.pivot[7]` 在 5 任务抽样中 `vx/vy/angle_z` 几乎全 0；FoldTowel 的 `angle_z` 到 0.8 rad、`height` 0.68–0.74；StackBowls `vx` 最大 0.032。**协同主要是上半身协同，底盘/步态不是主线**。

## 2. 问题形式化

### 2.1 POMDP

```text
任务 k ∈ {1..32}
episode τ = (o_1, a_1, ..., o_T, a_T)
o_t = (I_t^1..I_t^4, q_t^L, q_t^R, g_t^L, g_t^R, l, k)
a_t = (Δq_t^L, Δq_t^R, Δg_t^L, Δg_t^R)  或  (Δp_t^L, ΔR_t^L, ...)
success(τ) ∈ {0,1}
step(τ) ∈ [0,100]
```

目标：

```text
max_π E_{k∼p(k), τ∼p(τ|k,π)} [ success(τ) ]
s.t. 单模型、单 checkpoint、无 per-task 权重
     episode 时间/安全/API 约束
```

步骤分只用于 tie-break 和诊断，不作为主 objective。训练时可以加 step 辅助损失，但早停/选模以 success 为主。

### 2.2 协同变量

对每帧定义：

```text
r_t^h ∈ {idle, support, actor, handover}   # 角色
m_t ∈ Δ^4                                 # U/S/A/I/F 软模式
p_t ∈ {approach, grasp, transport, insert, release, verify}
a_t^{h,*} ∈ [0, 5.5]                      # 目标孔径
c_t = (nodes, edges, active_phase)         # 约束图
```

BCC 输出 `(r_t, m_t, p_t, a_t^*, c_t)`；MCAE 以这些为条件；CSR 用它们做门控。

### 2.3 假设与非目标

假设：

1. 官方数据/接口与 2026-10-25 版本一致；
2. 夹爪开度可观测，孔径是有效的接触代理；
3. 双手 EE 位姿在同一时间戳上可比；
4. 任务语言/评分步骤可用于相位分割；
5. 单模型可以在 32 任务上联合训练。

非目标：

- 多指灵巧手；全屋数字孪生；步态/足端规划；每任务 LoRA；运行时 MPC/RL；无力传感器的精确力控。

### 3.3 约束图示例

**T10 PlugCharger（I）**：

```text
phase approach:
  support(left, strip); actor(right, plug)
  relative_pose(left, right, Δp*≈strip 插口上方)
phase insert:
  support(left, strip, force=power, aperture≈3.3)
  actor(right, plug, force=precision, aperture≈1.8)
  align(plug, strip, axis=z, clearance=2mm)
  phase_lag(left, right, 0)
phase verify:
  settle(0.3s); check(plug_seated); release(right)
```

**T19 ZipUp（A）**：

```text
phase align:
  support(left, bag, aperture≈0.7)
  actor(right, zipper, aperture≈0.75)
  relative_pose(left, right, Δp*≈拉链起始点)
phase zip:
  support(left, bag, drift_tol=5mm)
  actor(right, zipper, direction=+y)
  phase_lag(left, right, ≈0.5s)
phase verify:
  check(zip_closed); release(both)
```

**T16 FoldTowel（F）**：

```text
phase flatten:
  support(left, towel); support(right, towel)
  relative_pose(left, right, Δp*≈毛巾宽度)
phase fold_1..4:
  actor(left|right, corner); support(other, towel)
  regrasp allowed; aperture≈1.2/0.9
phase place:
  both actor; transport to side; release
```

### 3.4 验证协议

1. 每任务随机抽 50 条 episode（或每任务 10 条，覆盖 5 个模式）；
2. 两名标注者独立看腕部视频 + 夹爪开度，标角色/模式；
3. 计算 Cohen's κ；目标 > 0.7；
4. 若 κ < 0.6，放宽模式定义（U/S/A/I/F → 协调强度低/中/高）；
5. 用标注结果校准阈值；报告阈值敏感性（±20%）。

### 4.2 BCC：协同编译器

```text
输入：演示 τ，任务 k，评分步骤 S_k，阈值 θ
输出：每帧 (m_t, r_t, p_t, a*_t, c_t)

1. 逐帧特征
   cL_t = 1[gL_t < 3.8]; cR_t = 1[gR_t < 3.8]
   vL_t, vR_t = EE 线速度（base 系，30fps）
   b_t = cL_t & cR_t

2. 相位分割
   events = 夹爪 close/open 边沿 + EE 速度谷值 + S_k 边界
   phases = 用 HMM/Viterbi 在 events 上切分
   允许一个评分步骤包含多个 phase

3. 角色标注
   if b_t and ||vL_t||<0.008 and ||vR_t||>0.03: rL=support, rR=actor
   elif b_t and ||vR_t||<0.008 and ||vL_t||>0.03: rR=support, rL=actor
   elif b_t: rL=rR=actor
   elif cL_t: rL=actor, rR=idle
   elif cR_t: rR=actor, rL=idle
   else: both idle
   handover = 双手同时 grasp，随后一手 open 且另一手保持 grasp
   用 Viterbi 平滑，转移先验由训练集统计

4. 模式软分类
   features = [both, sa, ρ*, lag, switches, regraspL, regraspR,
               |apL−apR|, len]
   m = softmax(MLP(features))
   训练标签 = 人工抽检 + 规则弱标签；损失用 KL/CE

5. 约束图
   nodes = {L, R, obj_1..obj_n, fixture_1..fixture_m}
   edges = support, relative_pose, phase_lag, aperture, approach_vector
   edges 按 phase 激活；support edge 带 drift_tol

6. 输出
   m_t (5 维), r_t (4 维 one-hot/soft), p_t (6 维),
   a*_t (2 维), c_t (edge list + phase)
```

复杂度：离线 O(T) 每 episode；在线只跑模式分类器 + 查表约束图，<5ms。

**与同期工作的差异**：Co-VLA、Coordi-π、TwinVLA 等把协同作为端到端学习目标/表示（[S13][S14][S15]）；BCC 把协同先编译成可审计的角色/相位/约束，再条件化策略。这样做的好处是：1-DOF、无力的 UniBot 上，失败可以定位到「角色错 / 相位错 / 孔径错 / 约束丢」，而不是只有一个黑盒 loss。

### 4.3 VDX：虚拟灵巧

#### 4.3.1 ACG 孔径条件抓取

```text
输入：物体宽度 w，抓取类型 q，当前孔径 g
输出：目标孔径 a*，闭合速度 η

a* = w + clearance(q)
  power:     clearance=4mm, a*∈[3.0,3.8]
  precision: clearance=2mm, a*∈[1.2,1.8]
  pinch:     clearance=1mm, a*∈[0.5,1.0]
闭合：
  g_{t+1} = g_t − η
  若 |g_t − g_{t−1}| < ε 或 g_t ≤ a*：停止
  ε 由负载/速度估计；薄物体允许 over-close 到 0.05
滑移：
  if |g_t − a*| > 0.5 and ||v_EE|| < 0.01 for 2 frames:
      二次夹紧（η×1.5）或重抓
```

#### 4.3.2 力型选择

| 物体 | 力型 | 目标孔径 | 理由 |
|---|---|---:|---|
| 插排/盒子/碗 | power | 3.0–3.8 | 大接触面，抗扰动 |
| 插头/网线/钥匙 | precision | 1.2–1.8 | 小目标，需对齐 |
| 拉链头/纸/薄片 | pinch | 0.5–1.0 | 薄，易滑 |
| 易碎物（药瓶/耳机） | precision + 限速 | 1.5–2.0 | 防压碎 |

#### 4.3.3 环境支撑

- **桌面**：把物体压住再拉/拧；
- **架子**：把容器顶住再插；
- **另一只手**：支撑手固定目标，操作手动作；
- **重力**：利用物体自重落位，减少夹持精度要求。

#### 4.3.4 重抓/手递手

触发：

1. 滑移（孔径/视觉）；
2. 对齐误差 > 5mm 或 5°；
3. 相位 stall > 2s；
4. 支撑手需要换位。

重抓点选择：腕部近场图像 + 当前物体位姿 + 可达性；优先抓物体重心附近/刚性边。

手递手：双手同时 grasp → 释放一只手 → 另一只手保持相对位姿 → 继续。用于 T18/T28。

### 4.4 CRM：协同富集演示挖掘

#### 4.4.1 特征与分层

对每条 episode 计算 BCC 特征 `[both, sa, ρ*, lag, switches, regraspL, regraspR, |apL−apR|, len]`；按主模式分层；每个 batch 至少包含 U/S/A/I/F 各 1 条（不足时按比例）。

#### 4.4.2 权重

```text
w_i = (1 / freq(m_i))^α · (1 + β · coordination_score_i)
coordination_score_i = z(both) + z(sa) + z(switches) + z(regrasp)
α = 0.3, β = 0.5, w_i capped at 3
```

不把 U 任务降权，只做角色 token dropout；否则模型会忘记单臂任务。

#### 4.4.3 增强

| 增强 | 参数 | 目的 |
|---|---|---|
| joint time warp | 0.8–1.2× | 保持双手同步 |
| relative pose jitter | ±5mm / ±3° | 容忍标定误差 |
| support-object translation | ±2cm | 官方 human_1 类型 |
| one-arm delay | 0–0.5s | 官方 human_4 类型 |
| aperture perturbation | ±0.3 | 滑移/薄物 |
| occlusion | 腕部 10–30% 区域 | 遮挡鲁棒 |
| role token dropout | 10% | 防止只依赖 token |

### 4.5 CSR：运行时协同监督

#### 4.5.1 监控量

| 监控 | 计算 | 触发阈值 | 动作 |
|---|---|---|---|
| support drift | 支撑手 EE 位移 / 支撑物视觉位移 | >5mm / >8mm | 暂停 actor，re-anchor |
| aperture slip | `|g_t − a*|` 且 EE 静止 | >0.5，2 帧 | 二次夹紧/重抓 |
| phase stall | 相位进度 | 2s 无进展 | 退回上一相位/重试 |
| insertion fail | 插入尝试 | 3 次 | 螺旋搜索/换接近向量 |
| human proximity | 人手进入工作区 | 腕部/头部视觉 | 减速/后退/等待 |
| collision proxy | EE 与障碍距离 | <2cm | 限速/绕行 |
| timeout | 剩余时间 | <15s | 放弃长尾，保当前步骤 |

#### 4.5.2 门控

```text
CONTINUE：一切正常
PAUSE：支撑丢失/人手进入 → 保持当前位姿，等待
REGRASP：滑移/对齐误差 → 释放、抬高 2cm、重抓
RETRY：插入/相位失败 → 退回上一相位，换参数
RETREAT：碰撞/超时 → 后退到安全位，放弃当前子目标
```

#### 4.5.3 实现

- 10–20Hz；规则评估 <10ms；不训练；
- 输入：EE、夹爪、腕部图像（轻量检测/光流）、BCC phase；
- 输出：覆盖 action chunk 的门控信号；
- 安全：工作空间包围盒、速度上限、碰撞代理、人工急停。

### 4.6 CPE：协同扰动引擎

#### 4.6.1 事件语法

```text
event := translate(object, direction, magnitude, time)
       | remove(object, time)
       | undo(step, time)
       | delay(arm, duration, time)
       | swap_roles(time)
       | perturb_aperture(arm, delta, time)
       | occlude(camera, region, duration, time)
```

#### 4.6.2 官方备注解析

输入：`info.json` 的 `human_1_note` / `human_4_note`（[S4]）。

规则：

- 方向词：前/后/左/右/上/下 → `direction`；
- 对象词：杯/碗/盘/盒/网线/插口/锁/包/拉链/盖子/毛巾/电池/钉子 → `object`；
- 撤销词：之后/再/拿走/拉开/拧回/打开/拔起/放回 → `undo` 或 `remove`；
- 时间：默认在对应评分步骤完成后 0.5s；`human_4` 的 undo 事件绑定到该步骤的完成相位。

示例：

```text
T27 human_4「叠了第二个之后拿下第二个」
→ undo(T27.step2) at phase=release+0.5s

T19 human_4「拉上拉链之后拉开」
→ undo(T19.step2) at phase=verify+0.3s

T10 human_4「将插头拔起」
→ remove(plug) at phase=verify+0.5s  / 或 translate(plug, +z, 3cm)
```

#### 4.6.3 三层实现

1. **离线回放**：在演示上做对象平移/撤销/延迟；生成 `(o', a, recovery_label)`；
2. **仿真扰动**：轻量桌面仿真，注入事件，闭环；
3. **真机调试槽**：T19/T10/T26/T27/T16，按官方备注复现，验证 CSR。

### 4.7 MCAE：模式/角色/相位/孔径条件动作专家

#### 4.7.1 底座

- 首选：WLA-1.0-Base 6B（[S12]）；LoRA 微调；
- 备选：GR00T N1.5 / π0.5 级 VLA；
- 单模型、单 checkpoint；任务条件通过 language/task token，不训练 per-task 权重。

#### 4.7.2 输入

```text
visual: 4×RGB (480×640) → vision encoder
proprio: 14 arm joints + 2 grippers + 15 lower_body + 3 waist
language: task instruction (5 paraphrases)
tokens:
  m_t: 5 维 soft mode
  r_t: 4 维 role（左右各一）
  p_t: 6 维 phase
  a*_t: 2 维 aperture target
  c_t: 相对位姿/接近向量/相位滞后（12 维）
```

#### 4.7.3 结构

```text
shared vision-language trunk
        │
        ├── shared action trunk
        │      ├── left residual head  → left arm + gripper
        │      └── right residual head → right arm + gripper
        ├── auxiliary role head
        ├── auxiliary mode head
        ├── auxiliary aperture head
        └── auxiliary relative-pose head
```

双臂共享 trunk 保证协同；arm-specific residual 保留左右差异；辅助头只在训练时用（推理可丢）。

#### 4.7.4 损失

```text
L = L_flow(a | o, l, tokens)
  + λ1 L_CE(role)
  + λ2 L_CE(mode)
  + λ3 L1(aperture)
  + λ4 L1(relative_pose)
  + λ5 L_CE(phase)
```

建议：`λ1=0.1, λ2=0.1, λ3=0.05, λ4=0.1, λ5=0.05`；用不确定性加权或 GradNorm 调。

#### 4.7.5 训练配方

| 项 | 值 |
|---|---|
| 数据 | 33k episodes，32 任务，5 复述 |
| chunk | 50 步（约 1.67s @30fps） |
| batch | 32–64 |
| 精度 | bf16 |
| LoRA | rank 32–64，q/v/o |
| 步数 | 10–20k |
| 学习率 | LoRA 1e-3，head 1e-4（线性 warmup + cosine） |
| GPU | 1–2 张 24–80GB |
| 课程 | U → S → A/I/F；后期混合 |
| 验证 | 留出 episode + 留出任务（T05/T19/T32） |
| 早停 | 验证 success / 协同 F1，不只看 loss |

#### 4.7.6 推理

- 50-step chunk，0.3–0.5s（参考公开 6B LoRA 基线，[S24]）；
- chunk 重叠 10 步，CSR 10–20Hz 门控；
- 缓存视觉/语言编码；只重算动作头；
- 延迟预算：感知 50ms + 动作 350ms + 监督 10ms < 500ms。

### 4.8 CCPL：跨任务协同原语库

| 原语 | 前置 | 参数 | 后置 | 任务 |
|---|---|---|---|---|
| anchor | 支撑物可见 | 接触点、力型、孔径 | 支撑手稳定 | T10/T19/T26 |
| brace | 物体可压 | 压点、方向、力 | 物体不滑 | T16/T31 |
| pull | 一手固定 | 方向、距离、速度 | 目标位移 | T05/T30 |
| twist | 一手固定 | 轴、角度、力矩代理 | 盖子/钥匙转动 | T12/T14 |
| insert | 两物对齐 | 接近向量、深度、间隙 | 插入到位 | T10/T26/T32 |
| handover | 双手可抓 | 释放手、时机 | 换手完成 | T18/T28 |
| fold | 柔性物 | 折线、压点、次数 | 折叠完成 | T16/T31 |
| zip | 拉链头可见 | 方向、张力、速度 | 拉链闭合 | T19/T23/T31 |

CCPL 是 BCC 约束图的可调用子图，不是硬编码执行器；MCAE 仍输出低层动作，CCPL 提供参数和相位先验。

### 4.9 与 PILOT 终局层集成

| 组件 | 作用 | 与 DUET 的关系 |
|---|---|---|
| SSG | 32 任务评分步骤图 | 相位标签 + 恢复触发 |
| PGL | slot → 2D anchor → 6D pose | 终局放置目标 |
| OPT | K 演示释放位姿中位数 + 离散度 | 终局位姿先验 |
| SVL | settle-verify 闭环 | 插入/放置验证 |
| NRB | 官方 human 备注回放 | 恢复脚本 |
| L2L | 离线→调试槽→计分跑校准 | 评测协议 |
| DebugLoop | 不计分单任务调试 | A/B 测试 |

执行顺序：

```text
BCC → MCAE → CSR → PGL/OPT → SVL → 失败则 NRB/CCPL
```

### 4.10 单模型合规

- 一个 checkpoint；无 per-task 权重/LoRA/专家；
- 任务条件：language + task embedding + BCC token；
- 训练时所有 32 任务联合；不做任务特定微调；
- 审计：保存训练配置、数据清单、token 方案；提交前跑单模型检查脚本；
- 若使用外部预训练权重，需确认规则允许；默认只用官方 32 任务数据 + 公开底座。

## 5. 数据引擎

### 5.1 数据 schema

| 字段 | 维度 | 说明 |
|---|---:|---|
| `observation.state.left_arm` | 7 | 左臂关节 |
| `observation.state.right_arm` | 7 | 右臂关节 |
| `observation.state.left_gripper` | 1 | 左夹爪开度 |
| `observation.state.right_gripper` | 1 | 右夹爪开度 |
| `observation.state.left_ee_pose_gripper_base` | 6 | 左 EE 位姿（base） |
| `observation.state.right_ee_pose_gripper_base` | 6 | 右 EE 位姿（base） |
| `observation.state.left_ee_pose_gripper_torso` | 6 | 左 EE 位姿（torso） |
| `observation.state.right_ee_pose_gripper_torso` | 6 | 右 EE 位姿（torso） |
| `observation.state.lower_body` | 15 | 下半身 |
| `observation.state.waist_state_joint` | 3 | 腰 |
| `observation.state.recomputed_ee_valid` | 1 | EE 有效位 |
| `action.left_arm` / `right_arm` | 7 / 7 | 目标关节 |
| `action.left_gripper` / `right_gripper` | 1 / 1 | 目标开度 |
| `action.pivot` | 7 | `[vx, vy, angle_z, p3, p4, p5, height]` |

| `action.base_command` | 4 | 底盘 |
| `timestamp` | 1 | 秒 |
| `frame_index` / `episode_index` | 1 / 1 | 索引 |
| `task_index` | 1 | 任务 |

### 5.2 标签管线

```text
raw parquet
  → 按 episode 排序
  → 计算 grasp / speed / both / support-actor / corr / lag / switches
  → 相位分割（夹爪边沿 + 速度谷值 + SSG）
  → 角色标注（规则 + Viterbi）
  → 模式软标签（MLP / 人工抽检）
  → 约束图（每相位）
  → 输出 labels.parquet
```

每个 episode 输出：

```text
episode_id, task_id, mode_probs[5], role[ T×2 ], phase[ T ],
aperture_target[ T×2 ], relative_pose[ T×12 ], regrasp_events,
support_intervals, quality_flags
```

### 5.3 采样

- 分层：按任务 × 模式 × 难度；
- batch 约束：每个 batch 至少 1 条 A/F；
- 权重：`w_i` 上限 3×；
- 语言：每条 episode 随机采 1 条复述；
- 课程：先 U/S，后 A/I/F；后期混合。

### 5.4 增强

见 4.4.3。额外：

- **时间对齐**：双手共享 time warp，不做独立时间拉伸；
- **相对位姿 jitter**：只加在 EE 目标，不改变夹爪开度；
- **对象平移**：在图像/仿真中移动支撑物，标签同步；
- **角色 token dropout**：10% 训练样本随机 drop mode/role，迫使模型从视觉推断；
- **相机遮挡**：腕部 10–30% 区域，模拟 human 遮挡。

### 5.5 官方备注解析

```python
NOTE_PATTERNS = {
    "translate": ["移动", "移开", "向前", "向后", "向左", "向右", "向上", "向下"],
    "undo": ["之后", "再", "拿走", "拉开", "拧回", "打开", "拔起", "放回"],
    "remove": ["拿走", "拔起", "移开"],
}
```

解析输出：

```text
{task, human_id, object, event, direction, magnitude, anchor_step, delay}
```

人工复核 32 条备注；T31/T32 为空，用通用扰动补足。

### 5.6 质量控制

- `recomputed_ee_valid` 为 0 的帧：丢弃/插值；
- 夹爪开度越界/跳变：中值滤波；
- episode 长度 < 3s：标记短样本；
- 语言复述缺失：用任务名兜底；
- 人工抽检 50 条/任务，检查角色/相位标签；
- 训练前跑 32 任务覆盖率报告。

## 7. 运行时监督

### 7.1 状态估计

- EE 位姿：直接从 proprio 读；
- 夹爪开度：直接从 proprio 读；
- 支撑物/目标物：腕部图像轻量检测 + 光流；不依赖外部模型；
- 相位：BCC 预测 + CSR 计数；
- 人手：腕部/头部图像检测；进入工作区则触发。

### 7.2 失败分类

| 失败 | 现象 | 处理 |
|---|---|---|
| support loss | 支撑手位移/支撑物移动 | pause + re-anchor |
| slip | 孔径漂移/视觉滑移 | regrasp + 二次夹紧 |
| misalignment | 插入 3 次失败 | 螺旋搜索/换接近向量 |
| occlusion | 腕部视野丢失 | 用头部视角/本体估计 |
| human undo | 已完成步骤被撤销 | NRB 回放 + 重做 |
| timeout | 剩余 <15s | 保当前步骤/放弃长尾 |
| collision | EE 距障碍 <2cm | 限速/后退 |

### 7.3 安全

- 工作空间包围盒（base 系）；
- EE 速度上限；
- 夹爪力上限（命令层）；
- 碰撞代理（桌面/架子/已知物体）；
- 人手进入工作区：减速/后退/等待；
- 急停接口（如果平台提供）；
- 所有规则可关闭，便于消融。

## 8. 实验协议

### 8.1 离线

| 指标 | 目标 | 数据 |
|---|---|---|
| mode macro-F1 | >0.75 | 人工抽检 + 弱标签 |
| role F1 | >0.80 | 50 条/任务 |
| aperture MAE | <0.3 | 演示孔径 |
| relative pose MAE | <1cm / 5° | 演示 EE |
| phase accuracy | >0.75 | SSG 对齐 |
| coordination score correlation | >0.6 | 人工评分 |

### 8.2 调试槽

| 任务 | 模式 | 次数 | 指标 |
|---|---|---:|---|
| T19 ZipUp | A/F | 10–20 | success、support step、regrasp |
| T10 PlugCharger | I/A | 10–20 | insert success、孔径 |
| T26 PlugInEthernet | A/I | 10–20 | insert success、支撑丢失 |
| T27 StackBowls | S | 10–20 | stack success、重抓 |
| T16 FoldTowel | F | 10–20 | fold success、重抓 |

A/B：baseline（PILOT/WLA）vs DUET；同一任务、同一初始条件、交替运行。

### 8.3 计分跑

- 320 trials；
- 指标：overall success、overall step、per-task、per-axis、per-mode；
- 记录失败类型（support/slip/align/timeout/human）；
- 不挑任务、不挑 trial；
- 与占位榜只做弱比较，不宣称排名。

### 8.4 统计

- 成功率 SE ≈2.56pp（p≈0.3）；
- 目标 +5pp 需要配对任务 bootstrap；
- 每模式至少 40 trials 才能看模式级趋势；
- 报告 95% CI；不只看均值。

### 8.5 go/no-go

**Go**：

- T19/T10/T26 support/actor 步骤分 +10pp；
- 终局 success +5pp；
- U 任务（HangCup）无回归；
- CSR 延迟 <100ms；
- 单模型审计通过。

**No-go**：

- 协同 token 无增益；
- CSR 触发过频，完成时间 >1.5×；
- 回退 PILOT 终局层 + 轻量 ACG。

| 计分跑 | 2 次（中期 + 最终） |

## 10. 风险与合规

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 模式覆盖不全 | 中 | 中 | soft label + 抽检 + 兜底 U |
| 阈值敏感 | 高 | 中 | 多阈值敏感性分析；人工校准 |
| 角色标签噪声 | 中 | 中 | 双人标注 + κ>0.7 |
| 1-DOF 上限 | 高 | 中 | 只承诺虚拟灵巧 |
| 无力传感器 | 高 | 中 | 孔径/视觉/跟踪误差三路投票 |
| human 备注不完整 | 中 | 中 | 通用扰动补足 |
| CSR 保守 | 中 | 高 | 置信度门控 + 超时回退 |
| sim-to-real | 中 | 中 | 真机调试槽优先 |
| 外部数据政策 | 高 | 高 | 默认 OFF |
| 占位榜误导 | 高 | 中 | 只做弱先验 |
| 单模型审计 | 中 | 高 | 单 checkpoint、无 per-task 权重 |
| 180s 超时 | 中 | 中 | CSR 时间预算 |
| API 延迟 | 中 | 中 | 缓存 + chunk |
| 数据不均 | 高 | 中 | 分层采样 + 加权 |

**合规清单**：

- [ ] 单模型、单 checkpoint；
- [ ] 无 per-task 权重/LoRA/专家；
- [ ] 默认只用官方公开数据；
- [ ] 外部预训练权重仅在规则允许时使用；
- [ ] 不在评测集上训练/调参；
- [ ] 不在评测时联网/外部计算；
- [ ] 遵守 API 速率、工作空间、安全边界；
- [ ] 保存训练/推理配置，可复现；
- [ ] 提交前跑单模型审计。
