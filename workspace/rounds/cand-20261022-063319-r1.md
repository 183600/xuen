# 想法区 · 本轮：从 DUB-MCTS 到 X-DUB

**灵感词**：exponential-time algorithm / convex optimization / 形式化描述  
**起点**：文件中的 v0.1 DUB-MCTS。它已经搭好了「动作空间覆盖最优、CP 上界、双侧区间、前沿证书」的骨架；本轮不推翻它，只替换其中最薄弱的模块——下界。

## 直觉：v0.1 的瓶颈不是找解，而是证明

v0.1 的下界是 `max(关键路径, 工作量注水)`。这两个界分别忽略机器争用和优先约束，因此在「同步/汇合」结构上会同时失效。一个很小的例子：

```text
m = 2
p = (2, 2, 5, 5, 5, 5)
依赖：2 → 1 → {0, 3, 5}，2 → 4
```

`L_CP = 12`，`L_W = 12`，但 `OPT = 15`。MCTS/rollout 可以找到 15，却无法证明 15 是最优；v0.1 的 `[L, U]` 会停在 `[12, 15]`。这不是搜索不够努力，而是下界没有看见「时间窗口内的容量冲突」。

## 三个灵感词分别补哪一块

- **convex optimization**：给每个时间槽一个价格 `λ_t`。对候选截止期 `H`，在所有满足优先约束和截止期的开始时间向量中，找「按价格计算的最便宜调度」。如果连这个最便宜调度的加权占用都超过机器能提供的加权容量，那么 `H` 一定不可行。这个内层问题是**最小权闭包 / 最小割**；外层是最大化凹函数 `g_H(λ)`，即一个凸优化问题。任意一组 `λ` 只要让 `g_H(λ) > 0`，就是一个可独立检查的**不可行证书**。
- **exponential-time algorithm**：精确搜索仍然是对 v0.1 动作树的 branch-and-bound，最坏情况指数时间；它不承诺新的最坏情况复杂度，而是承诺「在强下界剪枝下，用指数搜索换一个可证明的最优值」。小残差子问题再用 `k_small` 规模的指数精确子求解器闭合。
- **形式化描述**：算法不只返回一个数，而是返回一棵**证明树**：终端节点带可行调度，剪枝节点带对偶价格证书，内部节点带「动作已覆盖」的检查条件。一个独立的 checker 可以逐条验证；当根被关闭时， incumbent 就是 OPT。

## 核心方案：X-DUB

把 v0.1 的四个模块重新分工：

1. `LB_X(σ)`：新的下界模块。先算廉价的 `LB_CP/LB_W`；若还不足以剪枝，再调用 `CERTIFY(σ, U-1)`：用时间价格对偶证明「从 `σ` 出发不可能优于 `U`」。
2. `X-EXACT`：指数时间 B&B。按 `LB_X` 做 best-first 扩展；所有动作都保留（只做机器对称和完全相同状态的去重），因此继承 v0.1 的覆盖性；小残差调用 `EXACT-SMALL`。
3. `DUB-MCTS`：保留 v0.1 的 UCT/rollout，但降级为**上界发生器**。它只负责找可行解、更新 `U`，不再承担「统计引导能否证明最优」的责任。
4. `PROOF`：证明树。`L = U` 或前沿耗尽时，输出 `(incumbent, frontier, {λ_v})`；checker 验证每个剪枝节点的 `g_{U-1}(λ_v) > 0`，每个终端节点的调度可行，内部节点的动作覆盖完整。

这样，即使 UCT 的统计引导仍然不如随机重启，X-DUB 的正确性和证书也不受影响；MCTS 只影响「多快找到好上界」。这是对 v0.1 最大风险（UCT 有效性存疑）的结构性回应，而不是继续调参。

## 本轮要验证的命题

1. **对偶证书可采纳**：若 `g_H(λ) > 0`，则不存在 makespan ≤ H 的可行调度；因此 `L_D = max(L_0, 1 + max{H : ∃λ, g_H(λ)>0}) ≤ OPT`。
2. **内层 oracle 精确**：带优先约束和截止期的开始时间最小化可以编码成最小权闭包，最小割给出精确的 `g_H(λ)`。
3. **新下界严格强于 v0.1 的根下界**：在构造例上 `L_0 = 12`、`L_D = 15 = OPT`；区间价格 `λ_t = 1 (t∈[5,14))` 给出可手算的证书。
4. **指数 B&B 与 MCTS 可以解耦**：B&B 负责证书和剪枝，MCTS 负责上界；两者的正确性互不依赖。
5. **形式化证书可检查**：证明树的局部规则足以让 checker 验证 `U = OPT`，不需要信任搜索器的内部状态。

## 初步结果与边界

- 已做：90 个 `n∈{5,6,7}`、`m=2` 的随机 DAG 小实例，用「区间价格」子族（ER 界）作为对偶的可计算代理；精确解由穷尽 DFS 给出。结果：`L_0` 精确 79/90，ER 精确 80/90；ER 在 5 个实例上严格改进 `L_0`，其中 1 个直接闭合到 OPT。随机小实例大多太容易，不能说明平均性能，只验证了下界逻辑和证书格式。
- 构造例是更强的证据：`L_0 = 12`、`OPT = 15`，而 `λ_t = 1` 在窗口 `[5,14)` 上使 5 个被迫任务的总工作量 19 超过容量 18，直接证明 `H=14` 不可行。
- 尚未做：完整的时间价格对偶求解器（min-cut + 次梯度/割平面）、B&B 的大规模消融、PSPLIB 对照。这些是下一轮的实验主体。

## 下一轮增量方向

- 把 `CERTIFY` 从区间价格扩展到完整的分段常数/凸价格，使用 min-cut 内层 oracle 和 cutting-plane 外层。
- 用对偶价格做 reduced-cost fixing：若某个动作的 child 价格已经超过 `U`，直接固定删除。
- 在 B&B 中加入更强的支配关系和置换表；验证证明树 checker 的可靠性。
- 在 fork-join、partition、单长链+多短任务、PSPLIB 上做消融；与 CP-SAT/SCIP 对照证书时间和节点数。
- 再考虑随机工时：把确定性的 `g_H` 换成期望/分位数版本，重新证明可采纳性。

**当前方案最大的风险是：聚合容量对偶界仍然看不到机器身份和优先约束造成的空闲，而且求对偶本身可能比搜索还贵，导致 X-DUB 在大实例上既证不出最优也跑不完。**

# 产物区 · v0.2：X-DUB

> eXponential-time Dual-certified Upper/lower Bounds  
> 中文名：指数时间搜索 + 时间价格对偶证书的调度算法  
> 状态：完整设计稿；下界用「区间价格」子族做了原型验证；完整对偶求解器留到下一轮。

## 0. 版本关系与本轮增量

版本号接续文件中的 v0.1，表示设计增量而非循环轮次。文件中的 v0.1（DUB-MCTS）已经建立了：

- `P | prec | Cmax` 的 `(任务, 机器)` 动作空间，并证明它覆盖至少一个最优调度；
- `LB_CP`、`LB_W`、`L_F` 三个下界组件与前沿证书；
- CP 初始上界、UCT 主循环、rollout 与小型原型。

v0.2 **不推翻** 这些结论，只做三处增量：

1. **替换下界模块**：新增 `LB_X(σ)`，核心是时间价格对偶证书 `CERTIFY(σ,H)`。它不弱于 `LB_CP` 和 `LB_W`，并在构造例上严格更强；同时可以直接在节点上剪枝。
2. **新增指数时间精确核心**：`X-EXACT`，在 v0.1 的动作树上做 best-first branch-and-bound，最坏情况指数时间，但由对偶界剪枝；小残差用 `EXACT-SMALL` 闭合。
3. **重新分工 MCTS**：DUB-MCTS 从「搜索主体」降级为「上界发生器」。它只负责找可行解和更新 `U`；最优性证书由 `X-EXACT` + 对偶证书 + 证明树负责。

因此 v0.2 可以视为 v0.1 的 **下界替换 + 精确模式补全**：如果关掉对偶和 B&B，它退化为 v0.1；如果关掉 MCTS，它退化为一个带对偶剪枝的精确 B&B。

## 1. 问题、符号与复用的旧结论

### 1.1 形式化问题

```text
P | prec | Cmax
```

给定任务集 `V={1,...,n}`、工时 `p_i∈Z_{≥1}`、优先约束 `E⊆V×V`（DAG）、同构机器数 `m`。调度由开始时间 `s_i` 与机器 `μ_i` 组成，满足：

```text
(i,j) ∈ E  ⇒  s_j ≥ s_i + p_i
μ_i = μ_j  ⇒  [s_i, s_i+p_i) 与 [s_j, s_j+p_j) 不重叠
```

目标 `Cmax = max_i(s_i+p_i)` 最小；最优值记 `OPT`。

### 1.2 符号表

| 符号 | 含义 |
|---|---|
| `V,E,n,m,p_i` | 任务集、优先边、任务数、机器数、工时 |
| `pred(i), succ(i)` | 直接前驱/后继 |
| `r_i, q_i` | 静态 head/tail；`r_i` 是 `i` 之前的最长路径，`q_i` 是 `i` 之后的最长路径（均不含 `p_i`） |
| `L_CP` | `max_i (r_i+p_i)` |
| `L_W` | `ceil(Σ_i p_i / m)` |
| `L_0` | `max(L_CP,L_W)` |
| `σ=(S,A,c)` | 状态：已调度集、机器可用时间、完成时间 |
| `R(σ)` | 未调度集 `V\S` |
| `C(σ)` | `max_k A_k` |
| `Ready(σ)` | 前驱全部已调度的未调度任务 |
| `m_σ(t)` | 状态 `σ` 下时刻 `t` 可用的机器数 `|{k:A_k≤t}|` |
| `rel_i(σ)` | 已调度前驱的最晚完成时间；无则 0 |
| `lo_i(σ)` | 残余 DAG 的最早开始（动态 head，含已调度前驱） |
| `H` | 候选截止期（整数，全局 makespan） |
| `S_H(σ)` | 满足优先约束、release、deadline 的开始时间向量集合 |
| `u_t(s)` | 在 `t` 时刻正在处理的剩余任务数 |
| `λ_t` | 时间价格（对偶变量），`λ_t≥0` |
| `g_H(σ,λ)` | 拉格朗日内层最小值 |
| `L_D(σ)` | 对偶证书给出的下界 |
| `LB_X(σ)` | v0.2 的综合下界 |
| `U` | 当前 incumbent 的 makespan |
| `F` | 前沿（open 节点集合） |
| `k_small` | 精确子求解器的残差阈值 |

### 1.3 复用的 v0.1 结论

以下结论直接继承，不再证明：

- **动作覆盖性**：动作 `(i,k)`（`i∈Ready(σ)`，`k∈{1,...,m}`）在 `t=max(A_k, max_{j∈pred(i)} c_j)` 开始，允许主动空闲；从根出发的某条动作序列可达到一个最优调度（v0.1 命题 1）。
- **CP 初始上界**：按 `q_i` 降序的 CP 表调度得到可行 `U_0`，且 `U_0≤(2-1/m)OPT`（Graham）。
- **前沿下界**：若 `F` 是覆盖所有「可能优于 `U`」的剩余调度的切口，则 `min_{v∈F} LB(v)≤OPT`（v0.1 引理 2）。
- **机器对称/完全相同状态去重**是安全的；更强的支配关系需要单独证明。

v0.2 只替换其中的 `LB(v)`，并补上精确模式。

## 2. 新下界：时间价格对偶

### 2.1 动机

`LB_CP` 只看一条链，`LB_W` 只看总工作量。考虑

```text
m = 2
p = (2, 2, 5, 5, 5, 5)
依赖：2 → 1 → {0, 3, 5}，2 → 4
```

计算得：

```text
L_CP = 12,  L_W = 12,  OPT = 15
```

原因不是链不够长，也不是总工作量不够，而是：在时间窗口 `[5,14)` 内，有 5 个任务被迫进入，总工作量 19，而两台机器只能提供 18 个时间单位。v0.1 的静态下界看不到这种「窗口容量冲突」。

时间价格对偶的做法是：让算法自己选择一组价格 `λ_t`，把「窗口内的容量」变成「带权的容量」，再问「是否存在一个优先约束可行的调度，其加权占用不超过加权容量」。如果连最便宜的可行调度都超支，就得到了一个不可行证书。

### 2.2 剩余实例与截止期可行性

固定状态 `σ=(S,A,c)` 和候选截止期 `H≥C(σ)`。令：

```text
R = V \ S
rel_i = max(0, max_{j∈pred(i)∩S} c_j)          # 已调度前驱的释放时间
lo_i  = max( rel_i, max_{j→i, j∈R} (lo_j + p_j) ) # 残余 DAG 的最早开始（动态 head）
S_H(σ) = { s ∈ Z^R :
           lo_i ≤ s_i ≤ H - p_i,
           s_j ≥ s_i + p_i  for all (i,j)∈E, i,j∈R }
u_t(s) = Σ_{i∈R} 1[ s_i ≤ t < s_i + p_i ]
m_σ(t) = |{ k : A_k ≤ t }|
```

若 `s∈S_H(σ)` 且 `u_t(s)≤m_σ(t)` 对所有 `t` 成立，则把剩余任务按开始时间贪心放到空闲的可用机器上（区间图着色）可得到一个从 `σ` 出发、makespan ≤H 的可行调度；反过来，任何这样的调度都给出一个满足上述条件的 `s`。因此原问题在 `σ` 下存在 makespan ≤H 的调度，当且仅当存在满足容量约束的 `s∈S_H(σ)`。

> 说明：`m_σ(t)` 是「时刻 `t` 已经可用的机器数」，不是「当前空闲机器数」；已调度任务不占剩余容量。按开始时间贪心分配可用机器，可以证明 `u_t(s)≤m_σ(t)` 与机器可行性等价；2.3 再对这一容量约束做拉格朗日松弛，得到下界。

### 2.3 拉格朗日松弛

对每个时间 `t` 引入价格 `λ_t≥0`，把容量约束 `u_t(s)≤m_σ(t)` 松弛：

```text
L_H(s,λ) = Σ_{t=0}^{H-1} λ_t ( u_t(s) - m_σ(t) )
g_H(σ,λ) = min_{s∈S_H(σ)} L_H(s,λ)
```

**引理 1（对偶不可行证书）**：若 `g_H(σ,λ)>0`，则从 `σ` 出发不存在 makespan ≤H 的可行调度。

**证明**：若存在容量可行的 `s`，则对每个 `t` 有 `u_t(s)≤m_σ(t)`，故 `L_H(s,λ)≤0`。于是 `g_H(σ,λ)≤0`，与 `g_H>0` 矛盾。证毕。

注意：这里只需要弱对偶。`g_H` 是 `λ` 的逐点最小值，因此是凹函数；外层

```text
G_H(σ) = max_{λ≥0} g_H(σ,λ)
```

是一个**凸优化问题**（最大化凹函数）。我们不需要求出 `G_H` 的精确值：任何一组 `λ` 只要使 `g_H(σ,λ)>0`，就已经是一个可检查的证书。

### 2.4 内层 oracle：最小权闭包

对固定 `λ`，`g_H(σ,λ)` 是一个带优先约束和截止期的开始时间优化。它可以用最小割精确求解。

对每个 `i∈R`，令 `lo_i` 为 2.2 中残余 DAG 的动态 head，`hi_i=H-p_i`。由 `lo_j≥lo_i+p_i`，即使 `s_i=lo_i`，优先约束的基准情形也被 release 下界覆盖。若 `lo_i>hi_i`，则 `S_H=∅`。否则引入布尔变量：

```text
x_{i,t} = 1  ⇔  s_i ≥ t,      t = lo_i+1, ..., hi_i
```

由单调性，`x_{i,t}=1` 的集合是后缀。加入闭包约束：

```text
x_{i,t} ⇒ x_{i,t-1}                       (t = lo_i+2..hi_i)
x_{i,t} ⇒ x_{j,t+p_i}                     (对每条 i→j)
```

第二类约束中，若 `t+p_i>hi_j`，则 `x_{i,t}` 必须为 0（否则 `j` 会错过截止期）；若 `t+p_i≤lo_j`，则约束自动成立，可省略。闭包约束是「若选 `u` 则必选 `v`」的蕴含关系，标准地连一条 `u→v` 的无穷容量弧。

代价部分：定义

```text
w_i(s) = Σ_{u=s}^{s+p_i-1} λ_u
```

则

```text
w_i(s_i) = w_i(lo_i) + Σ_{t=lo_i+1}^{s_i} δ_{i,t} x_{i,t}
δ_{i,t} = w_i(t) - w_i(t-1) = λ_{t+p_i-1} - λ_{t-1}
```

于是最小化 `Σ_i w_i(s_i) - Σ_t m_σ(t)λ_t` 等价于最小化一个**线性的一元代价**加上常数，约束是闭包。把负的一元代价值用 source/sink 弧处理，构造标准的最小割图；最小割的源侧集合对应一个闭包，从而对应一个 `s`。

**引理 2（内层 oracle 精确）**：对任意 `λ≥0` 和 `H≥L_CP(σ)`，上述最小割给出的值加上常数等于 `g_H(σ,λ)`；且 `g_H(σ,λ)=+∞` 当且仅当 `S_H(σ)=∅`。

**证明草图**：

1. 给定 `s∈S_H`，令 `x_{i,t}=1[s_i≥t]`。单调性显然；若 `s_i≥t`，则 `s_j≥s_i+p_i≥t+p_i`，故对应的 `x_{j,t+p_i}=1`（若该变量存在）；代价展开逐项相等。因此可行 `s` → 闭包，且目标值相同。
2. 给定闭包，令 `s_i=lo_i`（若没有 true 变量）或 `s_i=max{t:x_{i,t}=1}`。单调性保证 true 变量是后缀，故 `s_i≤hi_i`。若 `s_i=lo_i`，由 `lo_j≥lo_i+p_i` 得 `s_j≥s_i+p_i`；若 `s_i>lo_i`，取 `t=s_i`，则 `x_{i,s_i}=1`，闭包给出 `x_{j,s_i+p_i}=1`，故 `s_j≥s_i+p_i`。代价展开同样相等。
3. 两个方向给出双射，因此最小割值等于内层最小值。`S_H=∅` 时闭包图出现「某变量既被强制为 1 又被强制为 0」或 `lo_i>hi_i`，返回 `+∞`。证毕。

最小割图的规模：节点 `O(nH)`，弧 `O((n+|E|)H)`。实现可用 Dinic；设单次最小割时间为 `T_cut(n,H)`。

### 2.5 外层：凸优化与证书搜索

`g_H(σ,λ)` 是凹函数。由 Danskin 定理，若 `s^k` 是 `g_H(·,λ^k)` 的一个最小点，则

```text
∂g_H/∂λ_t = u_t(s^k) - m_σ(t)
```

是一个次梯度。于是可用投影次梯度上升：

```text
λ^{k+1} = max(0, λ^k + η_k (u(s^k) - m_σ))
```

其中 `η_k` 可用 `η_0/√k` 或 Polyak 步长。每步做一次最小割；最佳（最大）的 `g_H(λ^k)` 被记录。

备选：cutting-plane / bundle。维护线性化

```text
g_H(λ) ≤ g_H(λ^k) + ⟨u(s^k)-m_σ, λ-λ^k⟩
```

解一个小型 master LP 得到候选 `λ`，再调用最小割求值。它比次梯度更稳，但实现更重；v0.2 把它列为下一轮的工程项。

```text
函数 DUAL-CERTIFY(σ, H, K)
────────────────────────────────────────────
1  if H < LB-CP(σ) then return PRECEDENCE
2  if H < LB-W(σ) then return WORK
3  λ ← 0                       # 或用父节点的 λ 热启动
4  for k = 1,2,...,K do
5      s ← MIN-CUT(σ, H, λ)     # 精确内层 oracle
6      v ← Σ_t λ_t (u_t(s) - m_σ(t))
7      if v > 0 then return DUAL(λ)
8      λ ← max(0, λ + η_k (u(s) - m_σ))
9  return FAIL
```

`FAIL` 只表示「这 K 次没有找到证书」，不表示 `H` 可行；因此它不会导致错误剪枝，只会让下界偏保守。

**定义（对偶下界）**：

```text
L_D(σ) = max( C(σ), L_0(σ), 1 + max { H ∈ Z : ∃λ≥0, g_H(σ,λ) > 0 } )
```

约定 `max ∅ = -∞`；最后一项为空时退化为 `max(C(σ),L_0(σ))`。由于每个被证明的 `H` 都满足 `H<OPT(σ)`，所以 `L_D(σ)≤OPT(σ)`。

**引理 3（可采纳性）**：`L_D(σ)≤OPT(σ)`。

**证明**：若认证集合为空，`L_D=max(C(σ),L_0(σ))≤OPT(σ)`（`C` 与 `L_0` 都是可采纳下界）。否则对任意使 `g_H>0` 的 `H`，引理 1 给出 `H<OPT(σ)`；由于 `H` 整数，`H≤OPT(σ)-1`。取最大再 +1，得 `1+max≤OPT(σ)`；再与 `L_0(σ)` 取 max 仍不超过 `OPT(σ)`。证毕。

**引理 4（支配旧下界）**：

```text
L_D(σ) ≥ max(C(σ), L_CP(σ), L_W(σ))
```

**证明**：

- `C(σ)`：任何剩余调度都不能让已完成部分倒退，故 `H<C(σ)` 直接不可行。
- `L_CP(σ)`：若 `H<L_CP(σ)`，则 `S_H(σ)=∅`，按引理 2 返回 `+∞`，证书成立。
- `L_W(σ)`：若 `H<L_W(σ)=ceil(W(σ)/m)`，取 `λ_t=1` 对所有 `t`，则对任意 `s∈S_H`，
  `L_H(s,λ)=Σ_i p_i - mH = W(σ)-mH >0`，故 `g_H>0`。

因此 `L_D` 至少覆盖旧的两个界。证毕。

### 2.6 区间价格、ER 与构造例

区间价格是 `λ` 的一个特殊子族：

```text
λ_t = c > 0   for t ∈ [a,b),    λ_t = 0 otherwise
```

此时内层最小值的一个下界来自「被迫进入 `[a,b)` 的任务」：若任务 `i` 满足

```text
lo_i ≥ a   and   H - q_i ≤ b
```

则任何满足 `S_H` 的开始时间向量都必须把它完全放在 `[a,b)` 内执行（`lo_i` 是残余 DAG 的最早开始，`H-q_i` 是 `i` 的最晚完成时间）。因此内层最小值 `g_H` 至少为 `c(Σ p_i - m(b-a))`（若某个 `p_i>b-a`，则 `S_H=∅`）。若这些任务的工时总和超过 `m(b-a)`，则 `g_H>0`，`H` 不可行。这正是经典的 **energetic reasoning（ER）** 区间界；它是 `λ= c·1_{[a,b)}` 的对偶证书。ER 只使用「完全被迫进入窗口」的任务，因此是一个保守子族；完整的时间价格对偶可以处理部分重叠、组合多个区间和不同价格，因此 `L_D≥L_ER`。

**构造例**：

```text
m = 2
任务:   0    1    2    3    4    5
p_i:    2    2    5    5    5    5
pred:  {1,2} {2}  ∅   {1}  {2}  {1}
```

静态量：

```text
r = (7, 5, 0, 7, 5, 7)
q = (0, 5, 7, 0, 0, 0)
L_CP = 12,  L_W = 12,  OPT = 15
```

根状态下 `lo_i=r_i`，因此下面的 `r` 表可直接用于 `lo_i` 条件。

取 `H=14`，`λ_t=1` 对 `t∈[5,14)`，其余为 0。被迫进入 `[5,14)` 的任务是 `{1,4,0,3,5}`：

```text
p_1+p_4+p_0+p_3+p_5 = 2+5+2+5+5 = 19
容量 = m·(14-5) = 2·9 = 18
19 > 18  ⇒  H=14 不可行
```

内层最小割可以返回 `s=(7,5,0,7,5,7)`，其加权占用为 19，`g_{14}=19-18=1>0`。这个内层调度在 `t=7,8` 使用了 4 台「聚合机器」，当然不是可行调度；但引理 1 只要求「所有优先约束可行的调度都至少付出 19 的加权占用」，而容量只提供 18，因此证书成立。

H=15 时存在可行调度（例如 `s=(7,5,0,9,5,10)`，`Cmax=15`），所以 `L_D=15=OPT`。这给出了一个 v0.1 根下界 `L_0=12` 无法证明、而 v0.2 可以证明最优的具体实例。

### 2.7 证书的可检查性

一个对偶证书是二元组 `(H, λ)`（可选地附上最小割的闭包/割作为内层最优性证据）。检查器只需：

1. 验证 `λ_t≥0`；
2. 在 `σ` 上构造闭包图，跑最小割，计算 `g_H(σ,λ)`；
3. 检查 `g_H(σ,λ)>0`。

如果检查器信任最小割的实现，它不需要信任搜索器的任何其他内部状态。若要把内层最优性也完全形式化，可把最小割的割集和闭包一起输出，检查器验证闭包可行、割容量等于目标值；这也是多项式时间的。

## 3. 指数时间分支定界：X-EXACT

### 3.1 搜索树

节点 `v` 保存状态 `σ_v`、未尝试动作集 `untried(v)`、子节点、以及可选的 `lb` 缓存。动作与转移完全复用 v0.1：

```text
a=(i,k),  i∈Ready(σ),  k∈{1,...,m}
t = max(A_k, max_{j∈pred(i)} c_j)
σ' = T(σ,a)
```

动作空间覆盖最优调度（v0.1 命题 1）。v0.2 不删除任何动作，除非：

- 机器对称：`A_k=A_l` 时 `(i,k)` 与 `(i,l)` 只保留一个；
- 完全相同的子状态哈希去重；
- 可选的、需要单独证明的强支配关系（v0.2 默认关闭）。

### 3.2 节点处理与剪枝

```text
函数 LB-X(σ, U)
────────────────────────────────────────────
1  L ← max(C(σ), LB-CP(σ), LB-W(σ))
2  if L ≥ U then return L
3  if CERTIFY(σ, U-1) succeeds then return U
4  return L
```

其中 `CERTIFY(σ,H)` 依次尝试：

1. 若 `H < LB_CP(σ)`：返回 `PRECEDENCE`（优先约束证书）；
2. 若 `H < LB_W(σ)`：返回 `WORK`（`λ=1` 证书）；
3. 否则运行 `DUAL-CERTIFY(σ,H,K)`：做 `K` 次最小割/次梯度（或 cutting-plane），若找到 `λ` 使 `g_H(σ,λ)>0`，返回 `DUAL(λ)`；否则返回 `FAIL`。

`LB_CP(σ)` 与 `LB_W(σ)` 按 v0.1 定义：动态 `es_i` 的关键路径界，以及从机器可用时间出发的工作量注水界。

**剪枝安全**：若 `CERTIFY(σ,U-1)` 成功，则从 `σ` 出发的所有调度的 makespan ≥U，不可能严格改进当前 incumbent。由于 `U` 单调不增，这个结论之后仍然成立。因此可以把 `v` 永久标记为 `PRUNED`。

### 3.3 分支、支配与精确子求解

```text
函数 X-EXACT(root, U0)
────────────────────────────────────────────
1  U ← U0;  best ← incumbent
2  root.lb ← LB-X(root, U)
3  F ← {root}
4  while F ≠ ∅ do
5      v ← argmin_{x∈F} x.lb            # best-first
6      if v.lb ≥ U then CLOSE(v); continue
7      if R(σ_v) = ∅ then
8          if C(σ_v) < U then U ← C(σ_v); best ← schedule(v)
9          CLOSE(v); continue
10     if |R(σ_v)| ≤ k_small then
11         val, sch ← EXACT-SMALL(σ_v)
12         if val < U then U ← val; best ← sch
13         v.lb ← val; CLOSE(v); continue
14     if v has no untried action then CLOSE(v); continue
15     a ← POP-UNTRIED(v)                   # 按 PRIOR 排序
16     σ' ← T(σ_v,a)
17     if DOMINATED(σ') then continue
18     v'.lb ← LB-X(σ', U)
19     if v'.lb ≥ U then mark v' PRUNED
20     else F ← F ∪ {v'}
21     if v has no untried action then CLOSE(v)
22 end while
23 L ← min_{x∈F} x.lb  (若 F=∅ 则 L=U)
24 return best, L, U
```

说明：

- `CLOSE(v)` 把 `v` 从 `F` 删除，并递归检查父节点是否已无 open 子节点且无未尝试动作；若是，则关闭父节点。
- `EXACT-SMALL` 对残差 `R(σ_v)` 做指数时间 DFS/DP，使用同一动作空间和 `LB_CP/LB_W` 剪枝；最坏 `O((m·k_small)^{k_small})`，对固定 `k_small` 是 `n` 的多项式。它返回从 `σ_v` 出发的精确全局 makespan。
- `POP-UNTRIED(v)` 按 v0.1 的 `PRIOR` 顺序取一个动作；顺序只影响效率，不影响完备性。
- `DOMINATED` 默认只做机器对称和状态哈希；强支配需要单独的正确性证明。

### 3.4 前沿与全局下界

`F` 是仍可能包含「优于 `U` 的调度」的 open 节点集合。定义

```text
L = min_{v∈F} LB-X(σ_v, U)        （F=∅ 时 L=U）
```

由 v0.1 的前沿引理（把其中的 `LB` 换成 `LB-X`），任何 `Cmax<U` 的调度都必须经过某个 `v∈F`，而该调度的 makespan ≥`LB-X(σ_v,U)≥L`。因此 `L≤OPT`。当 `L≥U` 或 `F=∅` 时，`U=OPT`。

### 3.5 证明树

为了让「最优性」可以被独立检查，算法在认证模式下输出一棵证明树 `Π`。每个节点 `v` 有一个状态：

- `TERMINAL`：`R=∅`，附带一个完整可行调度，makespan ≥`U`；
- `PRUNED`：附带某个 `H_v≥U-1` 的对偶证书 `λ_v`，满足 `g_{H_v}(σ_v,λ_v)>0`（通常取 `H_v=U-1`；若 `U` 后来下降，旧证书仍然更强）。`PRECEDENCE` 和 `WORK` 是两种特例：前者附一条长度超过 `H_v` 的关键链，后者附 `λ=1`；
- `EXACT`：附带 `EXACT-SMALL` 的精确值 `val_v≥U`（或 `val_v<U` 时已更新 incumbent）；
- `EXHAUSTED`：所有子节点都已关闭，且子节点覆盖了 `v` 的所有未被单独剪枝的动作；
- `LEAF-PRUNED`：某个动作的子节点被 `DOMINATED` 删除，附支配证明（v0.2 默认只允许机器对称/哈希，这两种支配的证明是局部的）。

证明树的检查规则：

```text
CHECK(v):
  若 v 是 TERMINAL: 验证调度可行且 Cmax ≥ U
  若 v 是 PRUNED:   验证 λ_v ≥ 0、H_v ≥ U-1 且 g_{H_v}(σ_v,λ_v) > 0
  若 v 是 EXACT:    验证精确子求解器返回 val_v ≥ U
  若 v 是 EXHAUSTED: 验证所有子节点 CHECK 通过，
                    且 v 的动作集合被 children ∪ pruned-actions 覆盖
```

```text
函数 BUILD-PROOF(root, U)
────────────────────────────────────────────
1  按后序遍历已探索的树
2  若节点是 terminal：标注 TERMINAL，附完整调度
3  若节点是 pruned（或仍 open 但 lb≥U）：标注 PRUNED，附 (H_v, λ_v) 或 PRECEDENCE/WORK 证据
4  若节点是 exact：标注 EXACT，附精确子求解器的值
5  若所有子节点已关闭且动作覆盖完整：标注 EXHAUSTED
6  返回带标注的树
```

如果算法因 `L≥U` 停止，`BUILD-PROOF` 先把每个 `lb≥U` 的 open 节点按其 `LB-X` 的来源标成 PRUNED；这些节点的证书已经由 `CERTIFY` 或廉价界给出，因此证明树仍然是闭合的。

如果根节点通过 `CHECK`，则由局部归纳：根节点不可能包含 makespan <U 的调度；而 incumbent 给出 `U`，所以 `U=OPT`。

> 证书大小 = 被探索的证明树 + 每个 PRUNED 节点的 `λ` 向量。最坏情况下树可以指数大；但每个被对偶剪掉的大子树只需要一个 `O(H)` 的证书。checker 的运行时间与证书大小成正比（每个 PRUNED 节点跑一次最小割；EXACT 节点重跑小规模精确子求解器）。这就是「形式化描述」的实际含义：证书可以独立验证，而不是只相信搜索器的日志。

### 3.6 精确模式与预算模式

- **精确模式**：关闭 MCTS，只运行 `X-EXACT` 直到 `F=∅` 或 `L≥U`。返回 `U=OPT` 和证明树。最坏情况指数时间；这是 `P|prec|Cmax` 的预期行为。
- **预算模式**：运行 `X-DUB` 主循环（下一节）`B` 步，返回 incumbent、`[L,U]` 和相对间隙。若中途 `L≥U` 或 `F=∅`，同样输出证明树并声明最优。

## 4. 与 DUB-MCTS 的整合：X-DUB

### 4.1 双队列主循环

v0.2 保留 v0.1 的 UCT 树，但增加一个「证书侧」的 best-first 扩展。两者共享同一棵搜索树。

```text
算法 X-DUB(G,p,m,B,K)
────────────────────────────────────────────
1  (r,q,L0) ← PRECOMPUTE(G,p,m)
2  π0,U0 ← CP-LIST-SCHEDULE(G,p,m)
3  best ← (U0,π0);  U ← U0
4  root ← NEW-NODE(σ0=(∅,0^m,⊥))
5  root.lb ← LB-X(root,U)
6  F ← {root};  L ← max(L0,root.lb)
7  for t = 1,2,...,B do
8      if F = ∅ then L ← U; break
9      if L ≥ U then break
10     if t mod K = 0 then
11         BBF-STEP(root)             # 证书侧：扩展 min-lb 的 open 节点
12     else
13         MCTS-STEP(root)            # 上界侧：UCT + rollout
14     UPDATE-FRONTIER(root)
15     L ← max(L, MIN-LB(F))
16 end for
17 if F = ∅ or L ≥ U then PROOF ← BUILD-PROOF(root,U)
18 return best, L, U, gap=(U-L)/max(1,L), PROOF
```

- `BBF-STEP(root)`：从 `F` 取 `lb` 最小的节点，按 `PRIOR` 弹出一个未尝试动作，创建子节点，计算 `LB-X`；若 `≥U` 则标记 `PRUNED`，否则加入 `F`。
- `MCTS-STEP(root)`：v0.1 的 `SELECT-UCT` + `ROLLOUT` + `BACKUP`；rollout 的完整调度更新 `U` 和 `best`。
- `K=1` 时每轮都做 `BBF-STEP`，退化为精确 B&B；`K=∞` 时退化为 v0.1 的纯 UCT（但下界仍可用）。
- `UPDATE-FRONTIER` 维护 `F`：节点首次出现未尝试动作时加入；动作耗尽或关闭时删除；`U` 下降后惰性清理 `lb≥U` 的节点。
- `L` 是单调的：`L ← max(L, MIN-LB(F))`，每个 `LB-X` 都是合法下界，取历史最大值仍合法。

### 4.2 对偶引导的先验

v0.1 的未尝试动作排序是

```text
PRIOR(i,k) = ( LB(child), -q_i, t, -p_i )
```

v0.2 可以加入父节点最近一次对偶证书的价格：

```text
price(i,k) = Σ_{u=t}^{t+p_i-1} λ_u
PRIOR(i,k) = ( LB-X(child), price(i,k), -q_i, t, -p_i )
```

解释：优先选择「子问题下界小、且占用便宜时间槽」的动作。它只是排序，不影响正确性；若没有可用的 `λ`，`price=0`，退化为 v0.1。

### 4.3 角色分离

这是 v0.2 最重要的结构性变化：

- **证书侧**（`X-EXACT` + `CERTIFY`）负责 `L` 和最终的最优性证明。它不依赖 UCT 的统计质量。
- **上界侧**（`DUB-MCTS`）只负责 `U`。即使 UCT 在确定性调度上不如随机重启，也只会让 `U` 下降得慢一些，不会产生错误的证书。
- **共享树**只共享状态和子节点；两侧的扩展策略独立，避免「统计引导弱 ⇒ 证书弱」的耦合。

这直接回应了 v0.1 的最大风险：MCTS 的统计引导是否有效，不再是算法正确性的前提。

## 5. 正确性论证

### 引理 1（对偶不可行证书）

已证于 2.3。

### 引理 2（内层 oracle 精确）

已证于 2.4。

### 引理 3（`L_D` 可采纳）

已证于 2.5。

### 引理 4（`L_D` 支配旧下界）

已证于 2.5。

### 引理 5（剪枝安全）

若 `CERTIFY(σ,U-1)` 成功，则从 `σ` 出发的所有调度的 makespan ≥U。由于 `U` 单调不增，之后也不会出现更优解；关闭该节点安全。

### 引理 6（动作覆盖）

v0.1 命题 1 保证动作空间至少包含一个最优调度。v0.2 只删除机器对称、完全相同状态和（默认关闭的）强支配动作；前两者不改变可达到的最优值。因此 `X-EXACT` 的树至少包含一个最优叶子。

### 定理 1（任意时刻区间）

在 `X-DUB` 运行的任意时刻，

```text
L ≤ OPT ≤ U
```

**证明**：`U` 来自可行调度（CP 或 rollout），故 `OPT≤U`。`L` 是 `L_0` 与前沿节点 `LB-X` 的最大值；每个 `LB-X` 由引理 3/4 可采纳，前沿覆盖性（v0.1 引理 2）给出 `L≤OPT`。证毕。

### 定理 2（精确模式终止即最优）

若 `X-EXACT` 因 `F=∅` 或 `L≥U` 终止，则 `U=OPT`。

**证明**：若存在 `Cmax<U` 的调度，由引理 6 和前沿覆盖性，它必须经过某个 open 节点 `v`，且 `LB-X(σ_v,U)≤Cmax<U`。这与 `F=∅` 或 `L=min_{v∈F}LB-X≥U` 矛盾。故不存在更优调度；结合 incumbent 可行性，`U=OPT`。证毕。

### 定理 3（证明树可靠）

若 `CHECK(root)` 通过，则 `U=OPT`。

**证明**：对证明树自底向上归纳。`TERMINAL` 节点没有更优完成；`PRUNED` 节点由引理 1 没有更优完成；`EXACT` 节点由精确子求解器没有更优完成；`EXHAUSTED` 节点的所有动作都被已关闭的子节点或已剪枝动作覆盖，因此也没有更优完成。归纳到根，根没有 `Cmax<U` 的完成；incumbent 给出 `U`，故 `U=OPT`。证毕。

### 定理 4（MCTS 不破坏正确性）

`MCTS-STEP` 只做两件事：在树上选择/扩展节点，以及用完整 rollout 更新 `U` 和 incumbent。它不使用任何未经验证的剪枝；若它使用 `LB-X` 过滤动作，该过滤由引理 5 保证安全。因此 MCTS 的任何行为都不会使 `[L,U]` 区间失效或使证明树不可靠。

### 定理 5（有限完备性）

搜索树有限（每个任务至多调度一次，动作数有限）；`X-EXACT` 的每次分支都前进一个任务；`EXACT-SMALL` 在有限残差上精确；剪枝只删除不可能优于 `U` 的子树。因此若预算无限，`X-EXACT` 最终关闭根并返回 `OPT`。最坏情况时间复杂度指数，这是 NP-hard 问题的预期行为。

## 6. 复杂度分析

### 6.1 单次操作

- **预处理**：拓扑排序 + head/tail，`O(n+|E|)`。
- **`LB_CP` / `LB_W`**：与 v0.1 相同，约 `O(n+|E|+m log(max A+W))`。
- **最小割**：图有 `O(nH)` 个节点、`O((n+|E|)H)` 条弧；Dinic 最坏 `O(V^2E)`，记作 `T_cut(n,H)`。实际实例中 `H` 可能很大，需用事件时间压缩或只对关键窗口建图。
- **`DUAL-CERTIFY`**：`K` 次最小割 + 次梯度更新，`O(K·T_cut(n,H) + K(n+H))`。
- **`CERTIFY`**：一次 `DUAL-CERTIFY`（或更廉价的 precedence/work 检查）。
- **`EXACT-SMALL`**：残差大小 `k_small`，最坏 `O((m·k_small)^{k_small})`；对固定 `k_small` 是 `n` 的多项式。
- **B&B 单节点**：`O(T_cut + b(n+m))`，其中 `b=m·|Ready|`。
- **MCTS 单次 rollout**：与 v0.1 相同，朴素 `O(n(n+|E|))`。

### 6.2 总计

设 `N` 为 B&B 物化节点数，`B` 为总预算：

```text
时间: O( N·(T_dual + b(n+m)) + B·n(n+|E|) )
空间: O( N(n+m) + |Π|·H )        # Π 为证明树中的证书
```

最坏情况：

```text
N = O( (m·n)^n )                 # 叶子数上界
```

因此 **认证总时间最坏指数**；对偶 oracle 本身是多项式时间，但会被调用很多次。v0.2 的贡献不是改变最坏情况复杂度，而是：

- 让每个节点有更强的、可证书化的下界；
- 让「找到最优」和「证明最优」可以分离；
- 在小/中实例上可能把指数搜索压缩成「小前沿 + 对偶证书」。

### 6.3 实现上的成本控制

- 只在 `LB_CP/LB_W` 不足以剪枝时调用对偶；多数节点会在廉价界处被剪掉。
- 对偶结果按状态哈希缓存；`U` 下降后旧证书仍然有效（因为它证明的是 `OPT≥U_old>U_new`）。
- 用父节点的 `λ` 热启动子节点；相邻状态的价格曲线通常接近。
- 在大实例上先用 ER 区间价格（`O(H^2 n)` 或事件时间上的 `O(n^2)`）做预筛，再决定是否跑完整最小割。
- 对 `H` 做事件时间压缩：只需在 release、deadline、`r_i+p_i` 等事件点之间的区间上取价格；相同价格的连续槽可以合并。

## 7. 实验设计与本轮初步结果

### 7.1 本轮已做：下界逻辑与证书格式

**实验 A（随机小实例，ER 子族）**

- `n∈{5,6,7}`，`m=2`，随机 DAG，边概率 0.35，`p_i∈[1,6]`；每个规模 30 个实例，共 90 个。
- 精确解：在 v0.1 动作空间上穷尽 DFS + 下界剪枝。
- 新下界：用区间价格（ER）作为完整对偶的可计算子族；它满足 `L_ER≤L_D≤OPT`，所以下表的 ER 结果是 X-DUB 下界质量的**保守**估计。
- 指标：`L_0` 是否等于 OPT、ER 是否等于 OPT、ER 是否严格大于 `L_0`。

| 规模 | 实例数 | `L_0` 精确 | ER 精确 | ER 严格优于 `L_0` | 其中 ER 闭合到 OPT |
|---|---:|---:|---:|---:|---:|
| n=5 | 30 | 27 | 27 | 1 | 0 |
| n=6 | 30 | 25 | 26 | 3 | 1 |
| n=7 | 30 | 27 | 27 | 1 | 0 |
| 合计 | 90 | 79 | 80 | 5 | 1 |

**诚实解读**：

1. 随机小 DAG 大多太容易，`L_0` 已经很紧；这张表不能说明平均性能，只验证「ER 下界不会超过 OPT」和「证书格式可用」。
2. ER 在 5 个实例上严格改进 `L_0`，其中 1 个直接闭合到 OPT；完整对偶只会更强。
3. 真正有说服力的是下面的构造例：它展示了 `L_0` 与 OPT 的 3 个单位差距，以及一个可手算的对偶证书。

**实验 B（构造例）**

```text
m=2, p=(2,2,5,5,5,5)
pred: 0←{1,2}, 1←{2}, 2←∅, 3←{1}, 4←{2}, 5←{1}
L_0=12, OPT=15
```

证书：`H=14`，`λ_t=1` 对 `t∈[5,14)`。被迫任务 `{1,4,0,3,5}` 的总工时 19，窗口容量 18，故 `g_{14}>0`，`H=14` 不可行；结合 `H=15` 的可行调度，`L_D=15=OPT`。

这个例子的价值：

- 它证明 v0.2 的下界可以严格强于 v0.1 的 `L_0`；
- 证书只用区间价格，说明完整对偶至少覆盖 ER；
- 证书可手算、可独立检查，适合作为 proof-tree checker 的第一个回归测试。

### 7.2 下一轮实验协议

**P1（正确性/对拍）**

- 500 个 `n≤8` 的随机 DAG，`m=2,3`，`p_i∈[1,10]`；
- 用穷尽 DFS 求 OPT；
- 对每个节点/根验证 `L≤OPT≤U`，所有 `PRUNED` 证书用独立最小割 checker 复核；
- 目标：零假证书、零错误剪枝。

**P2（下界强度）**

- `n=10..20`，`m=2..4`，随机 DAG 与 fork-join；
- 比较 `L_0`、`L_ER`、完整 `L_D`（K=50/200 次最小割）、CP-SAT/SCIP 的根界；
- 指标：根间隙 `(OPT-L)/OPT`、达到 `L=U` 的实例比例、单次 `CERTIFY` 时间。

**P3（B&B 效率）**

- `n≤15`，比较 v0.1 的 `LB_0` DFS、`X-EXACT` + ER、`X-EXACT` + 完整对偶；
- 指标：节点数、最小割调用次数、证书大小、总时间；
- 目标：对偶剪枝是否把节点数降低一个数量级以上。

**P4（anytime）**

- `n=20..60`，`m=2,4,8`，预算 1s/10s/60s；
- 比较 CP、DUB-MCTS、X-DUB、同预算随机重启、CP-SAT；
- 指标：incumbent gap、`[L,U]` 间隙、证书率、anytime 曲线、峰值内存；
- 统计：30 个种子，配对检验，报告均值/中位数/95% CI。

**P5（消融）**

- 对偶引导先验 vs UCT 先验；
- ER vs 完整对偶；
- `k_small∈{8,10,12}`；
- 强支配开/关；
- `K`（B&B/MCTS 交替比）的影响。

**P6（难例）**

- 无依赖 partition（m=2/3）；
- fork-join、单长链+多短任务；
- 强资源竞争、PSPLIB 风格实例；
- 专门寻找 `L_ER` 弱、但完整对偶可能强的结构。

**判定标准**：如果完整对偶在 fork-join/强竞争上不能稳定超过 ER，或者 `CERTIFY` 的成本使 B&B 总时间反而变慢，那么 v0.2 的核心假设（对偶界值得求解）就被证伪，应退回更廉价的 ER + 前沿证书。

## 8. 已知风险

1. **聚合容量对偶可能仍然弱**：`m_σ(t)` 抹掉了机器身份，也忽略了「某台机器被长任务占用导致优先约束任务无法启动」这类空闲。ER 构造例只说明它能捕捉窗口冲突，不能说明它在所有强依赖实例上都强。
2. **对偶求解可能比搜索还贵**：每个节点 `K` 次最小割，图规模 `O(nH)`；如果 `H` 大、节点多，`CERTIFY` 可能成为主要开销。缓解：廉价界预筛、ER 预筛、热启动、事件时间压缩、只在浅层/前沿节点跑完整对偶。
3. **内层是整数开始时间，不是 LP**：因此这是整数规划的拉格朗日松弛，不保证强对偶；`G_H` 可能小于 LP 界，次梯度也可能找不到正证书。好处是任何正证书都可靠；坏处是下界可能偏保守。
4. **B&B 仍是指数时间**：v0.2 没有改变最坏情况复杂度；如果对偶界不够强，`X-EXACT` 仍会爆炸。`k_small` 精确子求解器只是把常数级的残差闭合，不能解决大规模。
5. **MCTS 可能仍然没有显著收益**：角色分离保证了正确性，但不保证 anytime 上界比随机重启好；如果 UCT 在确定性调度上确实弱，X-DUB 的预算模式可能只是「B&B + 随机重启」。
6. **证明树/checker 的工程复杂度**：支配关系、前沿覆盖、`EXACT` 节点的可信执行都需要仔细实现；一个错误的 `PRUNED` 证书就会产生假最优。缓解：默认关闭强支配；所有证书用独立 checker 复核；用穷尽搜索对拍。
7. **模型假设**：整数工时、确定性、同构机器、无 release/准备时间。随机工时需要 chance node，`g_H` 的可采纳性证明不直接适用。
8. **数值与规模**：`λ` 可能很大，最小割容量需要高精度；`H` 可能很大，事件时间压缩是必须的工程项。
9. **完整对偶尚未实现**：本轮只用 ER 子族做了实验；完整对偶的强度、收敛速度、实际收益都还没有数据。这是下一轮最优先的验证项。
10. **理论贡献的边界**：v0.2 的主要贡献是「可证书化的对偶下界 + 指数 B&B 的证明树」，不是新的最坏情况复杂度界，也不是对所有实例都优于 v0.1。论文式表述必须避免过度声明。

---

## 9. 一句话最大风险

**当前方案最大的风险是：聚合容量对偶界仍然看不到机器身份和优先约束造成的空闲，而且求对偶本身可能比搜索还贵，导致 X-DUB 在大实例上既证不出最优也跑不完。**
