### 第 6 轮灵感驱动研究记录（新循环·第 1 轮）

**灵感词**：通用机器人平台、技术融合

**继承关系**：第 5 轮 CADVS-v5（IP-493~496）以「认证的生成式执行」（CGE）把 v4 的七硬门从离散规则提议推广到任意生成器：条件流匹配提议 π_θ^FM、LMEM-v2 记忆固化、FAMK 情感调制、EFA-v5 级联选证；定理 5/6/7/8 保证阈值只紧、证书与提议无关、固化有界、七锚完备，执行集 Exec_CADVS-v5 ⊆ Exec_CADVS-v4 ⊆ … ⊆ Exec_v29。本轮不推翻 v5，而是回答 v5 刻意回避的两个平台级问题：(a) 当系统从「单机器人单本体流水线」变成「异构本体、异构技能、多厂商可插拔的通用平台」时，认证的单位还是单条轨迹吗？(b) 当 VLA 基础模型、数字孪生、经典 MPC、车队协同「技术融合」进同一条执行链时，证书边界会不会在接缝处失效？两个灵感词统一为主题「认证的可组合平台」（Certified Composable Platform, CCP），形成 CADVS-v6（IP-497~500）。本轮自律：**七硬门一个不增**；平台级新增的不是门，而是「组合证明规则 + 准入一致性检验 + 不可转移证书」。执行集升级为 Exec_CADVS-v6 ⊆ Exec_CADVS-v5 ⊆ …。

**直觉与动机**：

1. **通用机器人平台 → 认证单位从「轨迹」上移到「能力契约」**。把平台想成具身智能的「操作系统 + 应用商店」：单个 App 是否安全，不取决于商店整体，而取决于 App 的权限清单 + 系统沙箱 + 组合规则。对应到机器人平台，认证的最小单位不是一条轨迹，而是能力契约 C=(P,G,κ,m,h,σ_emb)：前置条件、后置保证、七门向量与阈值、认证边际、有效期、本体签名。异构本体（机械臂、移动底盘、双臂、人形）必须先通过**准入一致性检验（conformance）**——证明其动力学类、执行器限、传感集落在各门假设域内——才能接入平台。平台的「通用性」来自接口统一，「安全性」来自契约可组合；二者是同一枚硬币的两面。

2. **技术融合 → 融合是「组合」而非「相加」，危险全在接缝**。VLA 基础模型输出技能/子目标 token，流匹配输出轨迹，经典 MPC 提供 BCK 平衡骨架，数字孪生提供带标定现实差距的证书神谕——这些不是四套并行系统，而是一条**分层组合链**。定理 6（证书不变性）天然外推：VLA 只是又一个提议源 π_VLA，提议可换、门不可换。真正的风险是接缝处的**涌现行为**：共享工作空间、共享人类、共享电力/网络、仿真到现实差距，会让「分量各自持证、合起来无人持证」。因此融合必须用 **assume-guarantee + 联合状态门提升**，把每个原子门从分量状态投影到联合状态并追加耦合谓词；分量近似与联合真值之差就是**融合残差 δ_fuse**。

3. **平台级反洗白 → 证书必须绑定组合图，不可跨图转移**。这正面回应 v5-R57 在平台上的放大：多个组件各自固化，组合可能把局部信任洗成整体信任。定义不可转移证书 Cert_G = Sign_sk(H(G, {C_v}, CalSet, τ^4))：证书只对签发时的能力图 G 有效，任何新增节点/边/版本变更都使证书失效并强制重认证。这让「建模内耦合」的洗白在结构上不可能（签名不可伪造）；未建模耦合由融合残差监控兜底——诚实边界是「只能检测、不能根除」。

**关键洞见**：v5 回答「单机、任意提议」；v6 回答「任意组合的机器/技能/技术，证书边界如何保持健全且单调」。把认证看成从「能力契约范畴」到「可执行集格」的**松弛幺半函子（lax monoidal functor）**：契约组合对应可执行集求交，松弛量恰好是融合残差 δ_fuse。七原子门原样冻结；平台新增的是组合证明规则与准入流程，而不是新的逐轨迹硬门。VLA/数字孪生/MPC 的融合被吸收进「提议源 + 证书神谕 + 平衡骨架」，均不改变门定义。

**形式化目标（增量）**：
1. 能力契约 C=(P,G,κ,m,h,σ_emb,v)；门提升算子 ↑_G：kc_i^↑(x_V)=kc_i(x_{proj_i})∧cpl_i(x_{N(i)})；证书代数 (⊗ 并行, ; 串行, ⊕ 选择)。
2. 跨本体契约态射 φ=(φ_S,φ_A) 与可移植边际 m_port；只允许「门谓词保持或收紧」的迁移，否则拒迁并回退重学。
3. 融合残差 δ_fuse(x)=d(联合门, 分量近似)、阈值 δ_max、数字孪生神谕与现实差距标定；超阈 fail-closed 转全联合评估或拒绝。
4. 定理 9（组合健全性/门提升）、定理 10（平台单调收缩）、定理 11（跨本体可移植界）、定理 12（不可转移/反洗白）。
5. 分层提议 π_VLA(σ|c)∘π_FM(x|c,σ)；证据融合取保守 meet（任一神谕 veto 即拒）。
6. Exec_v6(G)={x∈supp(π_fused): ∧_{i=1..7} kc_i^↑(x;τ^5)=1 ∧ Conform(G) ∧ CertValid(G)} ⊆ Exec_v5。

**本轮最大风险**：**组合导致的证书洗白**——平台用各分量在孤立语境下的证书，为一个涌现耦合从未被认证的融合系统背书；assume-guarantee 只覆盖被建模的耦合，融合残差监控（数字孪生/学习型神谕）自身有盲区，平台可能签发「组合上有效、实质上失真」的证书。

## 2. 关键算法骨架

### IP-497 CCK：能力契约核与门提升（组合证明，非运行期新门）

```python
@dataclass(frozen=True)
class CapabilityContract:
    """C=(P,G,κ,m,h,σ_emb,v)。平台最小认证单位是契约，不是单条轨迹。
    红线：κ 与 τ^5 引用 v5 冻结对象；组合只做合取与投影，不新增逐轨迹门。"""
    P: Predicate          # 前置条件（联合状态上的可判定谓词）
    G: Predicate          # 后置保证
    kappa: tuple          # (kc_1..kc_7) + τ^5（只读引用）
    m: dict               # 认证边际向量
    h: float              # 有效期（时间/步数）
    sigma_emb: EmbSig     # 本体签名
    version: str

def lift_gate(kc_i, proj_i, couplings_i, x_V) -> bool:
    """kc_i^↑ = 原子门∘投影 ∧ 耦合谓词。合取只增不减 ⇒ 提升后集合 ⊆ 边际集合。"""
    return kc_i(proj(x_V, proj_i)) and all(c(x_V) for c in couplings_i)

def compose(CA, CB, edge) -> "CapabilityContract | Reject":
    """证书代数：⊗ 并行 / ; 串行。良构性不成立即 fail-closed 拒绝。"""
    if not implies(CA.G, CB.P):          # assume-guarantee 前条件未清偿
        return Reject("PRE_UNPROVEN")
    if not resources_compatible(CA, CB, edge):  # 共享资源冲突（工作空间/人类/电力）
        return Reject("RESOURCE_CONFLICT")
    return CapabilityContract(
        P=CA.P,
        G=and_(CA.G, CB.G) if edge.parallel else CB.G,
        kappa=tuple(lift_gate(k, edge.proj[k], edge.cpl[k]) for k in CA.kappa + CB.kappa),
        m=meet(CA.m, CB.m), h=min(CA.h, CB.h),
        sigma_emb=product_sig(CA.sigma_emb, CB.sigma_emb),
        version=f"{CA.version}{'⊗' if edge.parallel else ';'}{CB.version}")
```

### IP-498 CECM：跨本体契约态射（可移植性 = 契约拉回 + 边际）

```python
@dataclass
class CrossEmbodimentContractMorphism:
    """把 A 上已铸证的技能迁移到 B。迁移不是复制权重，而是搬运契约。
    只允许门谓词保持或收紧；任何放宽都拒绝（否则违反单调收缩）。"""
    phi_S: Callable       # 状态映射 S_A -> S_B
    phi_A: Callable       # 动作映射 A_B -> A_A
    lip: float            # φ 的 Lipschitz 常数（离线估计）

    def transfer(self, skill_A, emb_B, CA, CB, m_port_min=0.0):
        # 契约拉回：A 的前条件必须蕴含 B 前条件的原像；B 的保证映射回后仍在 A 保证内
        if not subset(CA.P, preimage(self.phi_S, CB.P)):
            return Reject("PRE_NOT_PRESERVED")
        if not subset(image(self.phi_S, CB.G), CA.G):
            return Reject("POST_NOT_PRESERVED")
        if self.portability_margin(CA, CB) < m_port_min:
            return Reject("MARGIN_TOO_SMALL")
        return instantiate(skill_A, emb_B, self)   # 迁移后仍须过 PCA-v6 联合门
    # 诚实边界：臂↔人形等形态差异不可由线性/局部态射表达，必须重学而非迁移
```

### IP-499 FRM：融合残差监控（联合门 vs 分量近似的松弛量）

```python
@dataclass
class FusionResidualMonitor:
    """δ_fuse 是认证函子的松弛量：分量近似若低估耦合约束，则不安全。
    超阈 ⇒ 放弃近似，全联合评估；仍不过 ⇒ fail-closed 拒绝。"""
    twin: Any                 # 数字孪生神谕（带现实差距标定）
    delta_max: float = 0.05
    gap_cal: float = 0.02     # 标定后的 sim-to-real 残差上界

    def residual(self, x_V, gates, lifted) -> float:
        # 连续化：各门联合边际与分量边际之差的最大归一化值
        r = 0.0
        for kc, kc_up in zip(gates, lifted):
            r = max(r, (margin_marginal(kc, x_V) - margin_joint(kc_up, x_V)) / scale(kc))
        return max(0.0, r) + self.gap_cal

    def check(self, x_V, gates, lifted) -> str:
        d = self.residual(x_V, gates, lifted)
        if d <= self.delta_max:
            return "APPROX_OK"          # 分量近似可接受（保守）
        return "FULL_JOINT"             # 转全联合评估；再不过则拒绝
    # 诚实边界：数字孪生与学习型神谕均有盲区；δ_fuse 只能检测已被建模/采样的耦合
```

### IP-500 PCA-v6：平台证书总装（分层提议 + 联合门 + 不可转移证书）

```python
@dataclass
class PlatformCertificateAssemblerV6:
    """七原子门不变；平台层做「准入 + 组合 + 选证 + 绑定图签发」。"""
    cck: CapabilityContractKernel
    cecm: CrossEmbodimentContractMorphism
    frm: FusionResidualMonitor
    v5: EvidenceForgingAssemblerV5     # 复用 FMPP/LMEM/FAMK/VACK/BCK

    def select(self, x0, t_now, graph: CapabilityGraph, ctx):
        # 1) 准入与证书有效性：图哈希必须与证书绑定一致，否则拒绝
        if not self.cck.conform(graph):            # σ_emb 落在门假设域内？
            return Reject("CONFORMANCE_FAILED")
        if not self.verify_cert(graph):            # Cert_G 是否覆盖当前图？
            return Reject("CERT_NOT_TRANSFERABLE")
        # 2) 分层提议：VLA 技能 token → 流匹配轨迹（定理 6：提议可换，门不可换）
        sigma = self.v5.fmpp.propose_skills(ctx)   # π_VLA
        cands = self.v5.fmpp.propose(ctx, skills=sigma)  # π_FM
        # 3) 联合门提升 + 残差裁决
        out = []
        for x in cands:
            lifted = [lift_gate(k, graph.proj[k], graph.cpl[k], (x, graph))
                      for k in self.v5.kappa]
            mode = self.frm.check((x, graph), self.v5.kappa, lifted)
            if mode == "FULL_JOINT":
                ok = all(k(x, graph) for k in lifted)
            else:
                ok = all(k(x) for k in self.v5.kappa)
            if ok:
                out.append(x)
        if not out:
            return Reject("ALL_CANDIDATES_REJECTED")   # fail-closed，回退 v5 单机规则提议
        best = max(out, key=lambda x: joint_margin(x, graph))
        # 4) 签发不可转移证书（绑定图/版本/标定集/τ^4）
        cert = self.cck.sign(graph, self.v5.tau4, self.cal_set)
        return Forged(best, cert)
```

## 4. 正确性论证（增量更新）

### 引理 45（门提升的保守性）

**陈述**：对任意耦合谓词 cpl_i，kc_i^↑(x_V) ⇒ kc_i(x_{proj_i})。因此 Exec(lifted) ⊆ ∩_j Exec(C_j)。若耦合模型是**必要耦合**（joint guarantee 的每个失败模式都能被某个 cpl_i 捕获），则反向也成立，δ_fuse=0；否则 δ_fuse>0 度量「分量近似低估耦合」的程度。∎

**诚实边界**：健全性依赖耦合模型的完备性；漏建的耦合不会让 δ_fuse 报警，这是 FRM 的盲区。

### 引理 46（准入一致性的假准入界）

**陈述**：设门 i 的假设集为 A_i，conformance 套件在 A_i 上的检出功效为 1−β_i。若本体的真实参数偏离 A_i 超过容差，则假准入概率 ≤ ∏_i β_i。∎

**证明**：各门假设域独立采样测试；联合拒绝率由并集界。∎

**诚实边界**：测试集不可能穷尽所有分布外本体；β_i 只能经验估计。

### 定理 v6（平台组合健全、单调收缩与反洗白，总装）

**陈述**：在 v5 假设 (B1)~(B7) 及新增 (B8) 耦合模型对已建耦合完备、(B9) 数字孪生现实差距 ≤ gap_cal 下：
(i) Exec_v6(G) ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29（同分量）；
(ii) 组合健全：良构组合的融合系统持证，且 Exec(fused) ⊆ ∩_j Exec(C_j)（定理 9）；
(iii) 平台单调：增节点/边/技术只收缩执行集（定理 10）；
(iv) 跨本体：态射可表达且 m_port ≥ 0 时迁移持证，退化 ≤ L_φ·ε_φ（定理 11）；
(v) 反洗白：证书不可跨图转移，拼接证书无效（定理 12）；
(vi) 提议无关：VLA/流/规则等任意提议源不改变门边界（定理 6 外推）。

**证明**：(i) 由联合门合取加强 + Conform/CertValid 额外合取；(ii) 定理 9；(iii) 定理 10；(iv) 定理 11；(v) 定理 12；(vi) 定理 6。∎

**诚实声明**：(B8) 耦合模型完备性无法先验保证——未建模耦合是平台最大的原理性盲区；(B9) 数字孪生差距跨工况漂移；(iii) 契约版本漂移会累积维护负债（R52 的平台版）；(iv) 跨本体迁移只对态射可表达的本体成立，形态差异必须重学；(v) 证书绑定图会降低复用率，需在安全与效率间取舍。
