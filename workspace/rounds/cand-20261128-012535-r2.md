### 第 5 轮灵感驱动研究记录

**灵感词**：需求洞察、热管理

**继承关系**：第 4 轮 CADVS-v4（IP-489~492）在 v3 五锚点（3DCF/MSRG/HICK/EEK/LTEM/FFA）之上追加了价值锚 VACK（α_val）与平衡锚 BCK（BCC），形成七硬门 kc_evidence_forged_v4 = kc_coverage ∧ kc_physics ∧ kc_human ∧ kc_ee ∧ kc_mem ∧ kc_val ∧ kc_bal，fail-closed；软评分 ECS_v4 = ECS_v3 · η_val · η_bal；执行集嵌套 Exec_CADVS-v4 ⊆ Exec_CADVS-v3 ⊆ Exec_CADVS-v2 ⊆ Exec_CADVS-v1 ⊆ Exec_v29。本轮不推翻 v4，而是补上 v1~v4 始终缺席的「慢时域证据链」，形成 CADVS-v5（IP-493~496），执行集嵌套升级为 Exec_CADVS-v5 ⊆ Exec_CADVS-v4 ⊆ … ⊆ Exec_v29。

**直觉与动机**：

1. **需求洞察：从「规则是否合法」升级为「规则是否真的有用」**。v1~v4 所有锚点回答的都是「执行合法性」——覆盖是否盲、物理是否可证、人因是否否决、末点是否真实、历史是否可靠、价值是否对齐、交互是否稳定；它们共同默认了一个危险前提：「任务需求已被显式、正确地给定」。但真实用户指令是欠定的（underspecified）：「把杯子递给我」隐藏着「我渴了」「别洒」「杯子烫/易碎」「现在就要」等未言明需求，不同潜在需求对应完全不同的最优策略。HICK 只对显式指令做二元否决，VACK 只对价值做连续加权，二者都不建模「从演示与交互历史反推未言明需求」。引入需求洞察锚 RIK，用贝叶斯逆规划/意图推断从 `H=(演示D, 交互I, 上下文C)` 恢复潜在需求后验 `p(z|H)`，输出需求洞察证书 RIC，并同时约束「覆盖度」与「可辨识性」（后验熵），避免「用错误的需求收缩执行集」。

2. **热管理：从「单步稳定」升级为「可持续稳定」**。v4 的 BCK 在求解 Wrench 锥时默认扭矩集 `T` 恒定，但真实机器人受电机/驱动器/电池的热约束：温度是秒~分钟级慢变量，热降额使 `τ_max(T)` 随温度下滑，Wrench 锥随之收缩。控制环（1 kHz）看到的是标称能力，真实能力已被热悄悄削掉，形成「标称稳定、热致失稳」的隐性失效。引入热管理锚 TMK，以集总热网络 + EKF 在线观测并预测温度，输出热降额 `τ_derate`、热边际 `ξ_thermal`、热可行时域 `t_horizon`，给出热证书 TCC；并把 `τ_derate` 注入 BCK 的扭矩集，使平衡判定建立在真实热能力而非标称能力上。

3. **统一洞见：需求与热是同一类对象——慢时域潜变量**。需求是「人侧潜变量」，热是「机侧潜变量」，都不在 1 kHz 控制环的观测里，却都以「约束收缩」的方式决定执行集的真实边界：RIK 收缩「哪些规则值得做」（需求维度），TMK 收缩「能做多久/多强」（可持续维度）。v1~v4 建的是「快时域证据链」（毫秒级感知/控制），v5 补的是「慢时域证据链」（秒~分钟级需求/热）。二者共同把 v4 的「单步合法且稳定」升级为「长期有用且可持续」。

**关键洞见**：慢锚天然可异步评估——RIK 在规则准入阶段（秒级）运行，TMK 在慢环（10~100 Hz）运行并缓存 `τ_derate`/`kc_thermal` 标志，控制环只读缓存（O(1)），因此 v5 不仅没有加重 v4 的实时性硬伤（R49），反而通过「把热降额提前注入扭矩集」消除了热致失稳这一漏洞。九硬门 kc_evidence_forged_v5 = kc_coverage ∧ kc_physics ∧ kc_human ∧ kc_ee ∧ kc_mem ∧ kc_val ∧ kc_bal ∧ kc_req ∧ kc_thermal，fail-closed；软评分 ECS_v5 = ECS_v4 · η_req · η_thermal。

**形式化目标（增量）**：
1. 定义需求空间 `Z_req`、潜在需求变量 `z`、观测历史 `H=(D,I,C)`、后验 `p(z|H) ∝ p(H|z)p(z)`，及需求覆盖度 `α_req = E_{z~p(z|H)}[cover(π,z)]`、后验熵 `H_req = H(z|H)`。
2. 定义需求洞察证书 `RIC = (α_req, H_req, z_map, t)`，硬门 `kc_req = (α_req ≥ τ_req) ∧ (H_req ≤ H_max)`，软因子 `η_req = α_req · max(0, 1 − H_req/log|Z_req|)`。
3. 定义集总热网络 `C_th dT/dt = Q_gen(τ,q̇) − Q_diss(T,T_amb)`、降额曲线 `τ_derate(T)`、热边际 `ξ_thermal`、热可行时域 `t_horizon`；热证书 `TCC = (T_vec, τ_derate, ξ_thermal, t_horizon, t)`。
4. 定义热硬门 `kc_thermal = (ξ_thermal > 0) ∧ (t_horizon ≥ T_task) ∧ (τ_derate ≥ τ_needed)`，软因子 `η_thermal = min(ξ_thermal,1) · min(t_horizon/T_task,1)`。
5. 定义热-平衡耦合：BCK 扭矩集 `T ← T_nom ∩ {τ: τ ≤ τ_derate(T̂)}`，使 Wrench 锥 `W(T)` 随热状态单调收缩。
6. 定义 EFA-v5 九硬门与软评分 `ECS_v5 = ECS_v4 · η_req · η_thermal`。
7. 定义 `Exec_CADVS-v5 ⊆ Exec_CADVS-v4`：在 v4 每条路径上追加 `kc_req`（规则准入时）与 `kc_thermal`（慢环/控制环查询），故只缩不涨；并证明九硬门合取满足交换律，慢锚可异步并行评估而不改变判定结果。

**本轮最大风险**：**需求洞察把「推断出来的需求」当作硬门，一旦后验失配（需求幻觉/需求投射），fail-closed 会把执行集系统性地收缩到错误方向，且系统自身无法察觉、无法自我纠正**——热是可直接测量的物理量，需求却是从行为反推的隐变量，认识论上更脆弱。

### IP-493 RIK：需求洞察核（规则准入时，异步 ~10–100 ms，不在控制环）

```python
@dataclass
class RequirementInsightKernel:
    """RIK：贝叶斯逆规划/意图推断恢复潜在需求；kc_req 覆盖度+可辨识性双硬门"""
    tau_req: float = 0.65             # 需求覆盖硬门阈值
    H_max: float = 1.2                # 后验熵上限（nat）
    req_model: Any = None             # 逆规划/变分意图模型
    demo_buffer: DemoBuffer = None    # 演示缓冲
    n_particles: int = 256

    def infer(self, H_obs: History, context: Context, pi: Policy, t_now: float) -> RIC:
        """H_obs=(D,I,C)；pi 为待评估规则/策略；返回需求洞察证书"""
        # 1) 后验推断 p(z|H) ∝ p(H|z) p(z)（粒子滤波 / 变分推断）
        post = self._posterior(H_obs, context)          # 样本 {z^(s), w^(s)}
        # 2) 需求覆盖度：策略 π 在需求后验下的期望覆盖率
        alpha_req = float(np.sum([w * self._cover(pi, z)
                                  for z, w in zip(post.samples, post.weights)]))
        # 3) 后验熵：需求可辨识性（多峰/平坦 → 不可信）
        H_req = float(self._entropy(post))
        z_map = post.map()
        return RIC(alpha_req=alpha_req, H_req=H_req, z_map=z_map, t=t_now)

    def kc_req(self, ric: RIC) -> bool:
        """引理 43：通过 ⟹ 覆盖达标且需求可辨识"""
        return (ric.alpha_req >= self.tau_req) and (ric.H_req <= self.H_max)

    def eta_req(self, ric: RIC) -> float:
        denom = np.log(max(len(self.req_model.Z), 2))
        return float(ric.alpha_req * max(0.0, 1.0 - ric.H_req / denom))

    def _posterior(self, H, ctx): ...   # 逆规划：由动作反推最可能需求
    def _cover(self, pi, z) -> float: ...  # 需求 z 下 π 的满足比例
    def _entropy(self, post) -> float: ...
```

### IP-494 TMK：热管理核（慢环 10–100 Hz + 控制环只读缓存，目标 < 0.5 ms/慢周期）

```python
@dataclass
class ThermalManagementKernel:
    """TMK：集总热网络 EKF + 降额曲线 + 热预测时域；kc_thermal 硬门"""
    C_th: np.ndarray                 # 各关节集总热容
    R_th: np.ndarray                 # 各关节热阻
    T_max: np.ndarray                # 温度上限
    derate_curve: Callable           # τ_derate(T)：随温度单调不增
    horizon: float = 5.0             # 热预测时域 (s)
    safety_gamma: float = 1.3        # 预测安全系数
    thermal_ekf: Any = None

    def observe(self, T_meas, tau, qd, T_amb, t_now) -> TCC:
        # 1) EKF 融合温度测量与热模型，估计真实温度
        T_hat = self.thermal_ekf.update(T_meas, tau, qd, T_amb)
        # 2) 热降额与热边际
        tau_derate = self.derate_curve(T_hat)
        xi_thermal = float(np.min((self.T_max - T_hat) / (self.T_max - T_amb + 1e-9)))
        # 3) 恒功率预测：dT/dt = (Q_gen - Q_diss)/C_th，向前积分 horizon
        T_pred = self._predict_horizon(T_hat, tau, qd, T_amb, self.horizon)
        # 4) 距任一关节触降额阈值的时间，乘安全系数保守化
        t_horizon = self._time_to_derate(T_pred) / self.safety_gamma
        return TCC(T_vec=T_hat, tau_derate=tau_derate, xi_thermal=xi_thermal,
                   t_horizon=t_horizon, t=t_now)

    def kc_thermal(self, tcc: TCC, tau_needed: np.ndarray, T_task: float) -> bool:
        """引理 44：通过 ⟹ 热边际为正、降额后仍满足需求、热可行时域覆盖任务"""
        return (tcc.xi_thermal > 0.0
                and tcc.t_horizon >= T_task
                and bool(np.all(tcc.tau_derate >= tau_needed)))

    def eta_thermal(self, tcc: TCC, T_task: float) -> float:
        return float(min(tcc.xi_thermal, 1.0) * min(tcc.t_horizon / max(T_task, 1e-9), 1.0))

    def _predict_horizon(self, T, tau, qd, T_amb, horizon): ...
    def _time_to_derate(self, T_pred): ...
```

### 热-平衡耦合（IP-490 BCK 改造，控制环内 O(1) 注入）

```python
def bck_with_thermal(self, q, qd, tau, f_ext, contacts, tcc: TCC, t_now) -> BCC:
    """BCK 的扭矩集被热降额收缩：T ← T_nom ∩ {τ: |τ| ≤ τ_derate(T̂)}"""
    tau_limit = np.minimum(self.T_nom, tcc.tau_derate)   # 热致能力收缩，O(n_dof)
    # 后续 Wrench 锥求解使用 tau_limit，而非标称 T_nom
    return self._solve_balance(q, qd, tau, f_ext, contacts, tau_limit, t_now)
```

```python
    scf: SpatialCoverageFieldKernel
    msrg_cache: dict
    hic: HumanIntentCertificateKernel
    eek: EndEffectorFidelityKernel
    ltem: LongTermEpisodicMemory
    vack: ValueAlignmentCertificateKernel
    bck: BalanceControlKernel
    rik: RequirementInsightKernel
    tmk: ThermalManagementKernel
    mu_S: float = 0.75
    w: tuple = (0.4, 0.4, 0.2)

    def hard_gate(self, x, t_now, rule_id, hic, eec, bcc, tcc,
                  object_class, geo_sig, theta_domain_fp,
                  traj, context, H_obs, pi, tau_needed, T_task) -> tuple[bool, str]:
        # 优先级：HIC veto > 其余八硬门（慢锚 kc_req/kc_thermal 读缓存或慢环结果）
        if self.hic.veto_active(hic):            return False, 'HIC_STOP'
        if not self.scf.kc_coverage(x, t_now):   return False, 'COVERAGE_BLIND'
        s2rc = self.msrg_cache.get(rule_id)
        if s2rc is None or s2rc.verdict != 'accept' or s2rc.mu_pass < self.mu_S:
            return False, 'PHYSICS_UNPROVEN'
        if not self.eek.kc_ee(eec):              return False, 'EE_UNPROVEN'
        if not self.bck.kc_bal(bcc):             return False, 'BALANCE_UNSTABLE'
        if not self.tmk.kc_thermal(tcc, tau_needed, T_task):
            return False, 'THERMAL_UNSUSTAINABLE'
        pass_mem, eta_mem, novelty = self.ltem.query(object_class, geo_sig, theta_domain_fp, rule_id)
        if not pass_mem:                         return False, 'MEMORY_REJECT'
        vac = self.vack.evaluate(traj, context, t_now)
        if not self.vack.kc_val(vac):            return False, 'VALUE_MISALIGNED'
        ric = self.rik.infer(H_obs, context, pi, t_now)
        if not self.rik.kc_req(ric):             return False, 'REQUIREMENT_UNMET'
        return True, 'FORGED' + ('|NOVELTY' if novelty else '')

    def ecs_v5(self, x, t_now, rule_id, A_att=0.0, eta_mem=0.5,
               eta_val=0.5, eta_bal=0.5, eta_req=0.5, eta_thermal=0.5) -> float:
        base = (self.scf.gamma3d(x, t_now)**self.w[0]
                * getattr(self.msrg_cache.get(rule_id), 'mu_pass', 0.0)**self.w[1]
                * (1 + self.w[2]*A_att))
        return base * eta_mem * eta_val * eta_bal * eta_req * eta_thermal
```

## 3. 复杂度分析（增量更新）

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 | 实时性指标 |
|---|---|---|---|---|
| RIK infer | O(S·L·d) | O(S·d) | S=粒子数 256, L=历史长度 | ~10–100 ms（异步，准入阶段） |
| RIK kc_req / eta_req | **O(1)** | O(1) | — | < 0.01 ms |
| TMK observe | O(n_dof) | O(n_dof) | n_dof=7~14，集总模型 | ~0.1–0.5 ms（10–100 Hz 慢环） |
| TMK kc_thermal / eta_thermal | **O(1)** | O(1) | — | < 0.01 ms |
| 热-平衡耦合注入 | **O(n_dof)** | O(n_dof) | `min(T_nom, τ_derate)` | < 0.01 ms/周期 |
| BCK observe（含热收缩） | O(n_dof³) 精确 / O(n_dof) 近似 | O(n_dof²) | — | ~0.7–5 ms（沿用 v4 近似） |
| EFA-v5 硬门 | **O(1)** | O(1) | — | < 0.04 ms（不含 RIK/TMK 观测） |
| 端到端控制环增量（仅读缓存） | **O(1)** | O(1) | — | **< 0.05 ms（不恶化 v4）** |

**通信开销**：RIC 证书仅规则准入时产生（低频，~200 B）；TCC 慢环上报（10–100 Hz，~100 B/次，仅异常全量）；FFA Δ_i 扩充至 ~6–12 KB/站点；原始感知/温度数据不离站。

**实时性设计要点（对 v4 的 R49 的回应）**：
- RIK 完全异步化：准入阶段评估，控制环不调用 `infer`，只读缓存 `kc_req` 标志。
- TMK 运行在 10–100 Hz 慢环，控制环只读缓存 `τ_derate` 与 `kc_thermal`；注入 `τ_derate` 是 O(n_dof) 的逐元素 `min`。
- 热预测用恒功率解析积分（闭式），无需在线 QP；降额曲线可离线查表 + 线性插值。
- 结论：v5 把「慢变量」明确放在慢环，避免与 1 kHz 争预算。

## 4. 正确性论证（增量更新）

### 引理 43（需求可辨识性）

**陈述**：设每个潜在需求 `z` 至少可被某个演示动作区分（充分性），n 个观测后后验熵 `H(z|H)` 以 O(1/n)（满足强可辨识时指数）速率下降。当 `H(z|H) ≤ H_max` 时，需求覆盖度估计 `α_req` 相对真实期望 `α*` 的误差以概率 ≥ 1−δ 不超过 `sqrt(log(2/δ)/(2n)) + ε(H_max)`，其中 `ε(H_max)` 量化后验多峰带来的高估偏差。

**证明**：贝叶斯后验集中（Doob/后验一致性）给出后验向真实 `z*` 集中；熵界把多峰/平坦后验的偏差显式纳入；覆盖度是 `z` 的有界函数，对后验取期望的估计用 Hoeffding + 后验熵校正项。∎

**工程含义**：`kc_req` 不只看「覆盖够不够」，还看「需求是否可辨识」——后验太散（`H_req > H_max`）时宁可不做（fail-closed），避免用错误需求收缩执行集。

### 引理 44（热预测保守性）

**陈述**：设热参数误差 `‖ΔC_th‖ ≤ ε_C`、`‖ΔR_th‖ ≤ ε_R`，温度测量噪声 `σ_T`。以安全系数 `γ ≥ 1` 保守化后，真实触降额时间 ≥ 预测 `t_horizon` 以概率 ≥ 1−δ；`kc_thermal` 通过 ⟹ 任务期间不触热限。

**证明**：集总热模型对参数单调（C 越大升温越慢、R_th 越大散热越慢），取最坏参数包络得保守温度上界；EKF 误差协方差给出置信上界；`γ` 吸收未建模项。∎

### 定理 5（慢潜变量收缩与可分解性）

**陈述**：`Exec_v5 = Exec_v4 ∩ ReqAdm ∩ ThermalSust ⊆ Exec_v4`；若两新增硬门非恒真则严格 ⊂；收缩在需求维度与可持续维度可分解，且九硬门合取满足交换/结合律，评估顺序不影响判定。

**证明**：v5 在 v4 每条路径上追加 `kc_req`、`kc_thermal` 合取项，故只缩不涨；非恒真保证存在至少一条 v4 通过而 v5 拒绝的路径。合取的可交换/结合性由命题逻辑给出，故慢锚可异步并行评估。∎

### 定理 6（热-平衡耦合）

**陈述**：若 `T ≥ T_nom` 逐分量成立，则 `W(T) ⊆ W(T_nom)` 且 `ξ_wrench(T) ≤ ξ_wrench(T_nom)`。若 BCK 用标称 `T_nom` 而真实 `T > T_nom`，上报 `ξ_wrench` 高估真实余量 `Δξ ≥ 0`，存在 `kc_bal` 通过而真实失稳的漏洞；TMK 注入 `τ_derate` 后漏洞消除。

**证明**：`τ_derate(T)` 随 T 单调不增 ⇒ 可行扭矩集收缩 ⇒ Wrench 锥 `W` 收缩；`ξ_wrench = dist(0,∂W)/diam(W)` 对锥收缩单调不增。∎

### 定理 v5（执行集严格收缩与九锚点完备）

**陈述**：在 (B1)~(B6)（继承 v4）及新增 (B7) 需求可辨识（引理 43）、(B8) 热模型误差有界（引理 44）下：
(i) `Exec_v5 ⊆ Exec_v4 ⊆ … ⊆ Exec_v29`（严格收缩）；
(ii) 需求不满足/不可辨识的通过率由引理 43 界；
(iii) 热不可持续的通过率由引理 44 界；
(iv) 热致平衡误判漏洞由定理 6 消除；
(v) 九硬门构成有界分配格，合取为最大下界，fail-closed；慢锚可异步并行；
(vi) 九锚点互补完备（在 v4 七锚基础上补「需求」与「可持续性」两维，缺一不可）。

**证明**：(i) 由定理 5；(ii)(iii) 分由引理 43、44；(iv) 由定理 6；(v) 由证书格与交换律；(vi) 逐锚点反例构造（R53~R58）。∎

**诚实声明**：(B7)「需求可辨识」在真实交互中常被违反——用户需求多元、隐晦、动态变化，且可能自相矛盾，后验多峰使 `H_max` 难以达到，导致大量 fail-closed 拒绝（过度保守）；(B8) 集总热模型忽略空间温度梯度与相变/风扇非线性，极端工况误差大。缓解：需求侧主动学习（主动询问减少熵）、集成后验；热侧分布式测温 + 数据驱动残差修正 + 保守安全系数。

| 风险编号 | 描述 | 严重度 | 缓解措施 | 剩余风险 |

## 7. 本轮最大风险（最终确认）

**一句话**：**需求洞察把「推断出来的需求」当作硬门，一旦后验失配（需求幻觉/需求投射），fail-closed 会把执行集系统性地收缩到错误方向，且系统自身无法察觉、无法自我纠正**——热是可直接测量的物理量，需求却是从行为反推的隐变量，认识论上更脆弱。
