# 第 44 轮（新循环第 4 轮） · Chunk-Cert × Servo-Cert：把「动作分块」与「视觉伺服」纳入可验证证书闭环（四层架构 v9）

> 承接第 43 轮 v20（Persona-Cert × Concurrent-Cert）。v20 把「用户」与「并发」提升为一等公民，但仍压着两个关于**时间粒度**的未言明假设：**(H1) 认证粒度 = 执行粒度**——证书默认逐步签发、逐步执行，边际在每一步都被重新检查；而真实 VLA/扩散策略是**动作分块**（action chunking）：一次前向产生 K 步动作并开环执行，证书必须为未来 K 步背书。**(H2) 视觉只参与感知与提议，不参与证书的闭环保持**——而**视觉伺服**（visual servoing）恰恰是一个高频闭环，它既能把开环不确定性压小，也可能因为短视、特征丢失、交互矩阵病态而把机器人带出证书域。本轮灵感词「动作分块」「视觉伺服」精确命中这两个假设：**动作分块**把安全承诺从「下一步」拉长到「未来一段」，迫使我们证明的是**分块管（tube）**而不是**分块点**；**视觉伺服**提供把这段承诺收紧的高频手段，但它本身必须被证书门控，而不能替代证书。二者耦合处是本轮真正的新问题：**证书视界（certificate horizon）**——分块越长越省算力，但证书必须覆盖越长的开环窗口；伺服越快越安全，但占用实时预算、且其收缩性只在准静态/特征可见时成立。

## 0. 直觉与动机

**灵感 1（动作分块 → 「少想多做」必须为一段未来背书）**：直觉上，每次只预测一步、执行一步，机器人会陷入高频推理与抖动；一次预测 K 步、开环执行，则平滑、省算力、减少复合误差。但安全的视角完全反过来：**开环执行的 K 步里，没有任何新观测来纠正模型误差**，所以证书不能再只证明「a_t 安全」，而要证明「存在一个受控管 𝒯_0..𝒯_{K−1}，χ 在其中执行时状态始终不出管、边际始终 ≥θ」。开环下管径随 K 线性增长（r^open(k) ≤ r0 + k·w_max），这就是分块的**安全成本**；K 越大越省，但管越粗、越容易不可证。一句话：**分块把承诺拉长，证书必须把管算出来**。

**灵感 2（视觉伺服 → 高频小闭环把管径压小，但伺服是短视的）**：视觉伺服用图像误差 e=s−s* 直接生成速度 v=−λ_s L_e^+ e，频率远高于 VLM。它的价值在于**收缩**：每步误差按 ρ_eff 收缩，管径从「线性增长」变成「有界稳态」w_s/(1−ρ_eff)，于是同样的 θ 允许更长的 K。但它的危险同样直接：IBVS 是**图像空间短视**的——把图像误差压到零，不代表不撞障碍、不越关节限位；特征遮挡/出视野会让反馈瞬间消失；交互矩阵 L_e 依赖深度，深度误差与特征退化会把有效收缩率 ρ_eff 抬高，甚至 >1 而发散。因此伺服不能替代证书，只能作为**证书的执行器**：它负责把状态钉在管里，证书负责证明管是对的。一句话：**伺服把不确定性收紧，证书把伺服钉死**。

**灵感 3（耦合 → 证书视界与自适应分块）**：K 与伺服频率 f_s 是一对**时间预算的对偶**：K↑ 省 VLM 算力但要求更强的收缩；f_s↑ 更安全但挤占实时预算。把二者统一成一个**证书视界** H_cert：在管径不超过剩余边际的前提下，系统还能为多长的未来背书。于是分块长度不再是超参，而是**证书允许的最大值** K_t = min(K_max, K*, 预算上限)。这条思路还顺手解决了 v20 没处理的分块边界问题：重叠分块做时间集成时，若可容许集非凸，动作平均可能越界——必须「认证混合」或退化为「证书一致选择」，不能无条件平均。

**耦合升级**：CCC（分块证书编译器）把 VLA/扩散策略的分块编译成带管与视界的证书，并截断出可认证前缀；VSS（视觉伺服盾）以最高关键级运行，在线检查特征可见性、交互矩阵条件数、深度误差与延迟，并把状态约束在管内，失效即走中止阶梯；TCC（时间证书一致性）审计时间集成、分块边界与宏/微租约一致性。四层架构由此从 v8 的「个性化 + 并发」升级为 v9 的「个性化 + 并发 + **时间粒度/闭环伺服**」。

## 1. 形式化定义（增量：定义 44–49）

**定义 44（动作分块与分块证书）**：策略 π（VLA/扩散/流匹配）在 t0 由观测 x0 产生动作分块 χ=(a_{t0},…,a_{t0+K−1})，K 为分块长度，Δt 为执行步长。**分块证书** C_χ=(m0,K,𝒯,θ,f_s) 声称：从 x0 出发、以伺服频率 f_s 执行 χ（其间允许叠加伺服修正 u^s），对任意 k∈[0,K] 有 x_{t0+kΔt}∈𝒯_k 且 m(t0+kΔt)−λ·kΔt≥θ。**开环管**：r^open(k)≤r0+k·w_max（w_max 为每步扰动界），故纯开环分块必须用 K 换保守性。**命题**：若 𝒯 是含 χ 的受控不变管且每步盾检查通过，则分块执行期间证书保持。

**定义 45（视觉伺服证书与收缩管）**：图像特征 s∈R^m，误差 e=s−s*，交互矩阵 L_e(x)∈R^{m×6}，IBVS 控制 v=−λ_s L_e^+ e。**伺服证书** C_s=(ε_img,σ0,δ_depth,T_lat) 要求：‖e‖≤ε_img、σ_min(L_e)≥σ0、深度误差≤δ_depth、端到端延迟≤T_lat。在此条件下单步误差满足 ‖e_{k+1}‖≤ρ_eff‖e_k‖+w_s，且 ρ_eff≤ρ_nom+κ·δ_depth/σ0（深度误差与特征退化抬高有效收缩率）。**收缩管**：r^s(k)≤ρ_eff^k r0+(1−ρ_eff^k)/(1−ρ_eff)·w_s。**命题**：ρ_eff<1 时 r^s(k)→w_s/(1−ρ_eff) 与 K 无关；伺服把「开环线性增长」换成「有界稳态」，这是分块能变长的根本原因。

**定义 46（证书视界与自适应分块）**：**证书视界** H_cert(x0,χ)=max{kΔt : r^s(k)≤m0−θ−λ·kΔt}，**最大认证分块长度** K*=⌊H_cert/Δt⌋。自适应分块 K_t=min(K_max,K*,⌊B_rem/T_vlm⌋)，在算力与安全间取证书允许的最大值。**单调性**：K≤K* 才可执行，超出则截断为前缀；K↓ 更安全（收缩），K↑ 更高效（扩张）。**盲区**：若真实扰动 w>w_max 或 ρ_eff>1，H_cert 被高估，证书在「自认为有效」中静默失效——这是本轮最大风险的来源。

**定义 47（伺服门控与分块中止盾）**：伺服盾 S 每个伺服周期检查：(i) 特征可见性 V(s) 与数量；(ii) 条件数 σ_min(L_e)≥σ0；(iii) 延迟≤T_lat；(iv) 修正后状态仍在 𝒯_k。任一不满足则触发**中止阶梯**：继续纯伺服 → 截短分块重认证 → 回退规划器 → 安全停机。盾以最高关键级 κ=safety 运行（v20 定义 42），预算硬隔离。**命题**：盾把分块证书的静态假设变成运行时可检查的前提；中止阶梯只做单调降级，绝不放松 θ。

**定义 48（分块边界与时间集成 soundness）**：重叠分块时间集成 a_blend=Σ w_i a_i（Σw_i=1,w_i≥0）。**定理**：若每个 a_i 属于同一凸可容许集 A_adm，则 a_blend∈A_adm；若 A_adm 非凸（避障非凸域、关节限位并集），凸组合可能越界。故非凸约束必须「认证混合动作」或退化为「证书一致选择」（选单个已认证动作），禁止无条件平均。边界不连续度 ‖a_{t+K}−a_{t+K−1}‖≤Δ_max，否则触发重认证。

**定义 49（宏/微租约一致性）**：分块证书携带宏租约 ℓ^macro=(m0,τ0,λ,κ)，伺服每步签发微租约 ℓ^micro。**不变式**：任何微租约续期不得使宏租约的可用边际变大（m^macro(t)≥min over micro），微租约过期只允许单调降级（缩短 K、降速），不得静默延长宏租约。**命题**：宏/微租约一致性 ⟹ 不出现「伺服已失效但分块证书仍宣称有效」的撕裂状态（与 v20 定义 41、IP-58 快照读对接）。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-60 CHUNK-CERT-COMPILER（分块证书编译器 CCC）
1. **分块编译**：VLA/扩散策略输出 χ → 用伺服收缩模型构造受控管 𝒯_k 与 K* → 截断出可认证前缀、签发 C_χ。
2. **证书视界控制**：K_t 自适应（定义 46），在算力预算、任务时限、风险容忍之间取证书允许的最大 K。
3. **非凸动作集处理**：对避障/关节限位等非凸约束，用「证书一致选择」或「投影+再认证」，拒绝无条件平均。
4. **与几何/规划对接**：𝒯_k 作为时变安全管交给 IP-39/IP-49；分块前缀作为 IP-51 CAR 的宏转移。

### 2.2 IP-61 VISUAL-SERVO-SHIELD（视觉伺服盾 VSS）
1. **高频 IBVS/PBVS 伺服**：图像误差→速度修正，运行在最高关键级，预算硬隔离。
2. **伺服证书**：在线估计 σ_min(L_e)、特征可见性、深度不确定性、端到端延迟；ρ_eff 超阈值即报警。
3. **管 enforcement**：把修正后状态投影/约束在 𝒯_k 内；越界即中止。
4. **中止阶梯与恢复**：继续伺服 → 截短重认证 → 回退规划 → 安全停机；失败指纹回灌 IP-54/IP-55。

### 2.3 IP-62 TEMPORAL-CERT-CONSISTENCY（时间证书一致性 TCC）
1. **时间集成验证**：检测重叠分块的凸性前提，非凸时强制选择而非平均；输出混合证书或拒绝。
2. **边界一致性**：监测分块边界不连续度与速度/加速度跳变，超阈值触发重认证。
3. **宏/微租约审计**：验证定义 49 的一致性，检出「伺服失效但宏租约仍有效」的撕裂。
4. **反例生成**：把分块/伺服/边界反例回灌 SCV 与 CKB。

## 5. 本轮最大风险
**一句话**：视觉伺服的收缩证书只在「特征可见、交互矩阵良态、深度误差有界」的准静态假设下成立；一旦遮挡或动态场景使 ρ_eff 越过 1，而分块证书仍按视界公式宣称有效，就会形成「证书视界盲区」——伺服已退化为开环、宏租约却仍放行。故 E96/E98 必须设为红线，默认回退到 K=1 逐步认证 + 安全停机。

# 第 44 轮产物 · 创新点清单 v21：Chunk-Cert × Servo-Cert（CCC × VSS × TCC）× 可验证分块-伺服闭环（四层架构 v9）

## 2. 关键算法（伪代码）

### IP-60 CCC：分块证书编译、证书视界与自适应分块
```
def compile_chunk_certificate(proposal, x0, servo_cfg, theta, budget):
    K_max = proposal.max_chunk
    # 伺服收缩模型：深度误差与特征退化抬高有效收缩率（定义 45）
    rho = servo_cfg.rho_nom + servo_cfg.kappa * servo_cfg.depth_err / servo_cfg.sigma_min
    tube = [r_servo(k, rho, servo_cfg.w) for k in range(K_max + 1)]
    # 证书视界：管径不得超过剩余边际（定义 46）
    K_star = max([k for k in range(K_max + 1)
                  if tube[k] <= proposal.m0 - theta - proposal.lam * k * DT] or [0])
    K = min(K_star, K_max, budget.max_chunk)
    if K == 0:
        return None, AbortReason.NO_CERTIFIED_PREFIX
    return ChunkCert(m0=proposal.m0, K=K, tube=tube[:K + 1], theta=theta,
                     f_servo=servo_cfg.f, tau0=monotonic_now(),
                     lam=proposal.lam), proposal.actions[:K]

def adaptive_chunk_length(proposal, x0, servo_cfg, budget):
    cert, _ = compile_chunk_certificate(proposal, x0, servo_cfg, THETA, budget)
    # 效率/安全对偶：K 受证书视界与算力预算双重约束
    k_cert = cert.K if cert else 1
    k_budget = max(1, budget.vlm_budget // T_VLM)
    return min(k_cert, budget.max_chunk, k_budget)

def certified_select_or_blend(chunks, A_adm):
    # 非凸可容许集禁止无条件平均（定义 48）
    if not is_convex(A_adm):
        return certified_select(chunks)          # 只选单个已认证动作
    a_blend = weighted_sum(chunks)               # Σ w_i = 1, w_i >= 0
    if a_blend in A_adm and boundary_jump_ok(chunks):
        return a_blend
    return certified_select(chunks)              # 混合越界 -> 退化为选择
```

### IP-61 VSS：伺服证书、管 enforcement 与中止阶梯
```
def servo_shield_step(x, chunk_cert, s, L_e, depth_err, latency):
    # 1) 伺服证书前置条件（定义 45）
    if not feature_visible(s, chunk_cert) or sigma_min(L_e) < SIGMA0:
        return abort_ladder(chunk_cert, FeatureInvalid)
    if depth_err > DELTA_DEPTH or latency > T_LAT:
        return abort_ladder(chunk_cert, ServoCertViolated)
    # 2) IBVS 修正
    e = s - chunk_cert.s_star
    v = -LAMBDA_SERVO * pinv(L_e) @ e
    x_next = f(x, v, DT_SERVO)
    # 3) 管 enforcement（定义 47）
    k = chunk_cert.step
    if x_next not in chunk_cert.tube[k]:
        return abort_ladder(chunk_cert, TubeEscape)
    return v, renew_micro_lease(chunk_cert, x_next)

def abort_ladder(chunk_cert, reason):
    # 只允许单调降级：继续纯伺服 -> 截短重认证 -> 回退规划 -> 安全停机
    if servo_still_valid(chunk_cert):
        return ServoOnly()
    if shorter_prefix_exists(chunk_cert):
        return Recompile(shorter=True)
    if planner_available():
        return FallbackPlan()
    return SafeStop()

def renew_micro_lease(chunk_cert, x_next):
    m = estimate_local_margin(x_next)            # 本地快速边际
    return Lease(m=m, tau=monotonic_now(), lam=chunk_cert.lam, kappa=K_SAFETY)
```

### IP-62 TCC：时间集成、边界一致性与宏/微租约审计
```
def temporal_ensemble_certified(chunks, A_adm):
    if not is_convex(A_adm):
        return certified_select(chunks)
    a_blend = weighted_sum(chunks)
    cert_ok = certify_action(a_blend) and boundary_jump_ok(chunks)
    return a_blend if cert_ok else certified_select(chunks)

def boundary_consistency(prev_chunk, next_chunk):
    jump = norm(next_chunk.a0 - prev_chunk.a_last)
    return jump <= DELTA_MAX and accel_bound_ok(prev_chunk, next_chunk)

def macro_micro_lease_ok(macro, micro, t):
    # 定义 49：微租约不得放大宏租约可用边际
    m_macro = macro.m0 - macro.lam * (t - macro.tau0)
    m_micro = min(mm.m - mm.lam * (t - mm.tau) for mm in micro)
    return m_micro >= m_macro - EPS and all(mm.kappa >= K_SAFETY for mm in micro)
```

### IP-51/52/53 升级：分块-伺服感知的自动机与证书栈
```
def car_chunk_transition(e, x, cert, persona, t):
    # ChunkMode: CERTIFIED -> EXECUTING -> RENEW / ABORT
    if e.mode == EXECUTING and not macro_micro_lease_ok(e.macro, e.micro, t):
        return ABORT
    m = min(cert.m0 - cert.lam * (t - cert.tau0),
            persona_chunk_cap(persona),          # 谨慎人格 => 更短 K
            servo_margin(cert))                  # 管径不得吃掉边际
    return GUARD(m >= cert.theta[e])

def certify_light_v4(x, guards, persona, budget_us, criticality):
    # T-1: L0 查表 + 分块证书查询
    b = cert_lookup_L0(x)
    cert = chunk_cert_lookup(x)
    if cert and macro_micro_lease_ok(cert.macro, cert.micro, monotonic_now()):
        return b, cert, -1
    # T0: 伺服盾（最高关键级，HI 模式也不裁）
    if criticality < K_SAFETY:
        return downgrade_monotone(b), cert, -1
    v, lease = servo_shield_step(x, cert, features(x), L_e(x), depth_err(x), latency())
    return (b, cert, 0) if v is not None else (downgrade_monotone(b), cert, 0)
```

## 6. 本轮最大风险

**一句话**：视觉伺服的收缩证书只在「特征可见、交互矩阵良态、深度误差有界」的准静态假设下成立；一旦遮挡或动态场景使 ρ_eff 越过 1，而分块证书仍按视界公式宣称有效，就会形成「证书视界盲区」——伺服已退化为开环、宏租约却仍放行。故 E96/E98 必须设为红线，默认回退到 K=1 逐步认证 + 安全停机。
