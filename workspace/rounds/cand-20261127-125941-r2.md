### 第 4 轮灵感驱动研究记录（灵感循环第 2 轮）

**灵感词**：多机评测、用户画像

**直觉与动机**：

上一轮把 KEMPC 推进为 KT-MPC/KTCG：常识可解释、可跨任务迁移、权重可自适应。但有两个隐含前提没有被审视——证书的**评测单元**仍是一台机器人、一条轨迹；证书的**消费主体**仍是一个抽象的、无差异的操作员。本轮用「多机评测」和「用户画像」分别拆掉这两个前提。

1. **多机评测不是单机评测的求和。**
   单机的 Exec_v28 是若干安全谓词的合取，但合取在机群上不封闭：两台各自满足 USMC 的机器人，可能在共享工作区里互锁、争抢落脚点、遮挡彼此的感知，或在通信带宽/电池上形成耦合。也就是说，`∩_i Safe(π_i)` 并不蕴含 `Safe(π_1,...,π_n)`。必须引入显式的**交互证书** InterCert_{ij}，并且回答两个工程问题：
   - **组合爆炸**：n 台机器人有 O(n²) 对。若交互具有紧支撑（接触力、几何碰撞在距离 > ε 时为零），可用空间邻接图 G_ε 把检查量降到 O(n·k)；但 ε 不能拍脑袋，必须由可达性给出下界 ε_sound ≥ d_min + 2·v_max·H·dt，否则「当前很远、时域内会撞」的配对会被漏掉。
   - **异构性**：不同腿长、质量、关节限位、足底面积的机器人，其常识规则的适用性不同。上一轮的跨任务迁移因子 μ 只刻画「任务差异」，这里需要再乘一个**跨具身因子** ν_{i→j}，把知识从机器人 i 迁移到机器人 j 时显式打折；ν 低于阈值应直接禁用，而不是打折后勉强使用。

2. **用户画像不是给系统贴标签，而是给证书选择「投影」。**
   同一张证书，对新手、专家、风险厌恶者、风险偏好者的意义不同。固定 λ 和固定解释粒度会同时制造两种错误：对风险厌恶者过度保守（拖慢任务、诱发不信任），对风险偏好者过度信任（忽略告警、自动化偏信）。画像应形式化为 u=(ρ_u, τ_u, e_u, d_u, a_u, H_u)，分别表示风险容忍、信任校准、专业度、解释深度、自治偏好与历史。
   但这里有一条不可退让的设计原则：**画像只能调「软层」（舒适度、效率权重、解释粒度、建议自治级别），绝不能调「硬层」（结构安全、动力学可行、机间最小间距、支撑多边形）**。否则画像就从「人机适配」退化为「安全后门」。因此定义**安全底线不变式**：对任意画像 u，硬层判定 HardSafe(Π) 与 u 无关。

**关键洞见**：把评测对象从「单机轨迹」升格为「机群 × 用户」的联合执行集；证书从「存在性证明」变成「带硬底线的条件契约」——硬层对所有画像同一，软层按画像投影。多机评测解决「空间上的组合」，用户画像解决「人机之间的语义差」，二者共同把 KTCG 推向可部署的机群级准入。

**形式化目标（增量）**：
1. 机群计划 Π=(π_1,...,π_n)，机群执行集 Exec_fleet = {Π : ∀i USMC_i(π_i) ∧ ∀(i,j)∈G_ε InterCert_{ij}(π_i,π_j) ∧ FleetInv(Π)}。
2. 可达性安全的截断半径 ε_sound = d_min + 2·v_max·H·dt；紧支撑交互下截断为精确，非局部耦合（共享电量/带宽/通信连通性）改用 O(n) 的机群聚合不变式。
3. 跨具身迁移因子 ν_{i→j} = emb_sim(i,j)·dyn_sim(i,j)·ρ(φ_i,φ_j)·κ_age，扩展 CTKTP；ν 低于阈值时该规则对机器人 j 自动禁用，并输出具身迁移证书 ETC。
4. 用户画像 u 及其不确定性 Σ_u；硬/软分层门：HardSafe(Π) ⊥ u，SoftFit(Π,u) 依赖 u。
5. 解释投影 ExpReport_u = Proj_{d_u}(ExpReport)，只做粗化、不改变布尔判定与总惩罚归因。
6. 证明：(a) 安全底线不变性 Exec_FUCG(u) ⊆ Exec_hard，且对任意 u,u' 硬层相同；(b) 紧支撑 + ε_sound 下机群组合可靠性；(c) 画像误差只改变软层代价，其上界为 L_s·||u-û||，不改变安全概率；(d) 解释投影的判定保持性。
7. 实验：N∈{3,8,16} 异构双足共享工作区 + K≥24 操作员分层用户研究，分别测机群假接受率/时延与信任校准/自动化偏信/理解度。

**本轮最大风险**：**画像相对化的安全底线侵蚀**——一旦实现中让画像去调硬层阈值（哪怕只是「高信任用户可跳过确认」），误分类或对抗性画像就能把不安全计划认证成「符合该用户偏好」，而系统仍报告合规；机群会把这个单点错误沿交互图放大为编队级事故。它比上一轮的迁移负外部性更危险，因为错误被包装成了「个性化服务」。

## 2. 关键算法骨架（在 IP-462~466 骨架上扩展）

### IP-467 Fleet Interaction Certificate (FIC)

```python
@dataclass
class FleetInteractionCertificate:
    """FIC：机群级交互证书。属于硬层，不接受任何用户画像参数。"""
    n_robots: int
    d_min: float = 0.35          # 机间最小安全间距 (m)
    v_max: float = 1.2           # 机群最大速度 (m/s)
    horizon: int = 20            # 预测时域步数 H
    dt: float = 0.01             # 控制周期
    max_neighbors: int = 6       # 邻接图度数上限 k_max
    interaction_radius: float = None

    def __post_init__(self):
        if self.interaction_radius is None:
            # 可达性下界：当前相距再远，H 步内也可能进入 d_min
            self.interaction_radius = (
                self.d_min + 2.0 * self.v_max * self.horizon * self.dt
            )

    def build_neighbor_graph(self, plans: list) -> dict[int, list[int]]:
        """空间哈希 + 预测最小距离；只保留可能发生交互的配对。"""
        boxes = [self._swept_aabb(p.nominal_traj) for p in plans]
        candidates = self._spatial_hash_pairs(boxes, self.interaction_radius)
        graph = {i: [] for i in range(self.n_robots)}
        for i, j in candidates:
            if i >= j:
                continue
            d = self._min_predicted_distance(
                plans[i].nominal_traj, plans[j].nominal_traj
            )
            if d <= self.interaction_radius:
                graph[i].append(j)
                graph[j].append(i)
        for i in graph:
            # 度数截断只允许发生在「按预测最小距离排序后仍冗余」的邻居上；
            # 若截断会丢掉 d < d_min 的邻居，直接判 FIC 失败（见 admits_fleet）
            graph[i] = sorted(graph[i], key=lambda j: self._min_predicted_distance(
                plans[i].nominal_traj, plans[j].nominal_traj))[: self.max_neighbors]
        return graph

    def check_pair(self, pi, pj) -> bool:
        """InterCert_ij：最小间距 + 支撑面争用 + 感知遮挡。"""
        dist = torch.norm(
            pi.nominal_traj[:, :3] - pj.nominal_traj[:, :3], dim=-1
        ).min().item()
        if dist < self.d_min:
            return False
        if self._footprint_conflict(pi, pj):
            return False
        if self._occlusion_conflict(pi, pj):
            return False
        return True

    def check_fleet_invariants(self, plans, sensor_data) -> bool:
        """FleetInv：非局部耦合的 O(n) 聚合约束。"""
        if sum(p.power_draw for p in plans) > sensor_data["power_capacity"]:
            return False
        if sum(p.bandwidth for p in plans) > sensor_data["comm_capacity"]:
            return False
        if not self._comm_graph_connected(plans, sensor_data["comm_links"]):
            return False
        return True

    def admits_fleet(self, plans, sensor_data) -> bool:
        # 1) 每台机器人自身的硬证书（USMC + 单机 KTCG）
        for p in plans:
            if not p.usmc.admits(p.single_plan, sensor_data):
                return False
            if not p.single_gate.admits(p.single_plan, sensor_data):
                return False
        # 2) 交互证书：只查邻接图内的对；若被截断的邻居仍可能 < d_min，失败
        graph = self.build_neighbor_graph(plans)
        for i, nbrs in graph.items():
            for j in nbrs:
                if i < j and not self.check_pair(plans[i], plans[j]):
                    return False
            if len(nbrs) >= self.max_neighbors:
                for j in range(self.n_robots):
                    if j == i or j in nbrs:
                        continue
                    d = self._min_predicted_distance(
                        plans[i].nominal_traj, plans[j].nominal_traj
                    )
                    if d < self.d_min:
                        return False  # 截断不得吞掉真实风险
        # 3) 机群聚合不变式
        return self.check_fleet_invariants(plans, sensor_data)

    def truncation_exactness(self) -> bool:
        """紧支撑交互下，ε >= ε_sound 时被忽略的对贡献恒为 0。"""
        return self.interaction_radius >= (
            self.d_min + 2.0 * self.v_max * self.horizon * self.dt
        )
```

### IP-468 Cross-Embodiment Knowledge Transfer (CEKT)

```python
@dataclass
class CrossEmbodimentKnowledgeTransfer:
    """CEKT：把机器人 i 的知识迁移到机器人 j。属于硬层。"""
    nu_min: float = 0.35         # 低于阈值直接禁用，避免「打折勉强用」
    age_decay: float = 0.01      # 知识老化率 γ

    def migration_factor(self, kc, robot_i, robot_j, now) -> float:
        emb = self._embodiment_similarity(robot_i, robot_j)
        dyn = self._dynamics_similarity(robot_i, robot_j)
        rho = self._path_correlation(kc.phi, robot_i, robot_j)
        kappa = math.exp(-self.age_decay * (now - kc.created_at))
        nu = emb * dyn * rho * kappa
        return max(0.0, min(1.0, nu))

    def _embodiment_similarity(self, ri, rj) -> float:
        # 归一化形态向量 m = (leg_len, mass, dof, foot_area, torque_limit)
        mi, mj = ri.morphology_vector, rj.morphology_vector
        rel = torch.abs(mi - mj) / (torch.abs(mi) + torch.abs(mj) + 1e-6)
        return float((1.0 - rel.mean()).clamp(0.0, 1.0))

    def _dynamics_similarity(self, ri, rj) -> float:
        # 可达集 Hausdorff 距离的负指数；离线采样、在线按任务粗化
        h = self._reachable_set_hausdorff(ri, rj)
        return math.exp(-h)

    def transfer(self, kc, ri, rj, now):
        nu = self.migration_factor(kc, ri, rj, now)
        if nu < self.nu_min:
            return None  # 显式禁用，不产生 ETC
        # 保守迁移：后置条件阈值按 (1-nu) 收紧，杜绝「满迁移假象」
        tightened = self._tighten_postcond(kc.postcond, nu)
        return EmbodimentTransferredKC(
            name=f"{kc.name}@{rj.id}",
            precond=kc.precond,
            postcond=tightened,
            nu=nu,
            source=ri.id,
            target=rj.id,
            validated=False,
        )

    def validate_on_target(self, kc_t, rj, init_state, n_samples=50) -> bool:
        # 必须在目标具身上经验验证；未通过者永不进入硬层
        ok = 0
        for _ in range(n_samples):
            u_seq = [rj.dynamics.input_limits.sample()
                     for _ in range(kc_t.H)]
            traj = rj.dynamics.simulate(init_state, u_seq, kc_t.H)
            if kc_t.postcond(traj[-1]):
                ok += 1
        kc_t.validated = (ok / n_samples) >= 0.85
        return kc_t.validated

    def _tighten_postcond(self, postcond, nu):
        # 例：支撑面积阈值 A_min 变为 A_min / nu，间距阈值乘以 (1 + (1-nu))
        return lambda x: postcond(x) and self._margin_ok(x, nu)
```

### IP-469 User Profile Model (UPM)

```python
@dataclass
class UserProfile:
    user_id: str
    risk_tolerance: float = 0.5       # ρ_u
    trust_calibration: float = 0.5    # τ_u
    expertise: float = 0.5            # e_u
    explanation_depth: int = 2        # d_u ∈ {1,2,3}
    autonomy_preference: float = 0.5  # a_u
    history: list = field(default_factory=list)
    sigma: dict = field(default_factory=dict)  # Σ_u，逐维不确定度

    def soft_strictness(self) -> float:
        # 只影响舒适/效率，绝不返回硬层阈值；夹在 [0.6, 1]
        s = 0.5 + 0.5 * self.risk_tolerance
        return min(1.0, max(0.6, s))

    def autonomy_level(self) -> str:
        # 交互建议级别，不是安全阈值
        if self.autonomy_preference > 0.7 and self.trust_calibration > 0.6:
            return "advisory"
        return "confirm"

    def hard_layer_allowed(self) -> bool:
        # 显式禁止：画像不得暴露任何可用于放宽硬层的接口
        return False


class UserProfileModel:
    """画像估计与更新。对外只暴露软层参数与解释深度。"""

    def __init__(self):
        self.profiles: dict[str, UserProfile] = {}

    def estimate(self, user_id: str, explicit: dict = None,
                 behavior: dict = None) -> UserProfile:
        u = self.profiles.get(user_id, UserProfile(user_id=user_id))
        # 先验 + 显式问卷（风险/信任/专业度）+ 行为（接管率/时延/测验）
        if explicit:
            u = self._fuse_explicit(u, explicit)
        if behavior:
            u = self._bayes_update(u, behavior)
        # 不确定度高时向保守默认收缩（只影响软层与解释，不影响硬层）
        u = self._shrink_toward_prior(u)
        self.profiles[user_id] = u
        return u

    def update(self, user_id: str, event: dict):
        u = self.profiles.get(user_id, UserProfile(user_id=user_id))
        self.profiles[user_id] = self._bayes_update(u, event)

    def project_explanation(self, report, u: UserProfile):
        return Proj(report, depth=u.explanation_depth)

    def _shrink_toward_prior(self, u: UserProfile) -> UserProfile:
        # 逐维：若 sigma[k] 大，则向 0.5（保守默认）收缩
        for k, var in u.sigma.items():
            w = 1.0 / (1.0 + var)
            cur = getattr(u, k)
            setattr(u, k, w * cur + (1.0 - w) * 0.5)
        return u
```

### IP-470 User-Conditioned Cert Gate (UCCG)

```python
@dataclass
class UserConditionedCertGate:
    """硬/软分层门：画像是「投影选择器」，不是「阈值放宽器」。"""
    hard_gate: 'FleetUserHardGate'   # FIC + KTCG + CEKT；签名不含 profile
    upm: UserProfileModel
    s_min: float = 0.6
    audit_log: list = field(default_factory=list)

    def admits(self, fleet_plan, sensor_data, user_id: str) -> bool:
        # 1) 硬层：profile 绝不参与；失败即拒绝，后面无任何挽回路径
        hard_ok = self.hard_gate.admits_fleet(fleet_plan, sensor_data)
        self._audit(user_id, "hard", hard_ok, reasons=self.hard_gate.last_reasons)
        if not hard_ok:
            return False
        # 2) 软层：只影响舒适/效率/交互，不能反转硬层结论
        u = self.upm.estimate(user_id)
        soft_ok = self.soft_fit(fleet_plan, u)
        self._audit(user_id, "soft", soft_ok,
                    reasons={"s(u)": u.soft_strictness(),
                             "depth": u.explanation_depth})
        return soft_ok

    def soft_fit(self, fleet_plan, u: UserProfile) -> bool:
        # 软约束示例：加速度上限、任务节奏、解释深度；不触碰 d_min/支撑面
        a_max = 0.5 + 1.5 * max(self.s_min, u.soft_strictness())
        return fleet_plan.max_accel <= a_max

    def _audit(self, user_id, layer, ok, reasons=None):
        self.audit_log.append({
            "t": time.time(), "user": user_id, "layer": layer,
            "ok": ok, "reasons": reasons or {},
        })


def assert_profile_cannot_relax_hard(plan, sensor, upm, u_a, u_b):
    """代码级不变式：同一计划在两画像下硬层结论必须一致。"""
    gate = plan.hard_gate
    ok_a = gate.admits_fleet(plan, sensor)
    ok_b = gate.admits_fleet(plan, sensor)
    assert ok_a == ok_b, "hard layer leaked profile information"
```

### IP-472 Fleet-User Cert Gate (FUCG)

```python
@dataclass
class FleetUserCertGate:
    """FUCG：十证一体（单机 KTCG + FIC + CEKT + UCCG）。"""
    fic: FleetInteractionCertificate
    cekt: CrossEmbodimentKnowledgeTransfer
    upm: UserProfileModel
    uccg: UserConditionedCertGate

    def admits(self, fleet_plan, sensor_data, user_id: str) -> bool:
        # 1) 每台机器人的 KTCG（含 USMC/SMC/KT-MPC/IEKC/CTKTP/AKWA/DCC）
        for p in fleet_plan.robots:
            if not p.ktcg.admits(p.plan, sensor_data):
                return False
        # 2) 机群交互证书
        if not self.fic.admits_fleet(fleet_plan.robots, sensor_data):
            return False
        # 3) 跨具身迁移证书：未验证或 ν 过低的迁移规则一律拒绝
        for p in fleet_plan.robots:
            for kc in p.transferred_kcs:
                if kc.nu < self.cekt.nu_min or not kc.validated:
                    return False
        # 4) 硬/软分层画像门
        return self.uccg.admits(fleet_plan, sensor_data, user_id)
```

## 3. 复杂度分析（增量更新）

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 |
|---|---|---|---|
| FIC 邻接图构建 | O(n·H + n·k)（空间哈希粗筛 + 精确距离） | O(n·k) | n≤16, k_max≤6, H≤20 |
| FIC 交互检查 | O(n·k·H) | O(n·k) | 向量化后 n=16 时约 1920 个 pair-step |
| FIC 机群不变式 | O(n + \|E_comm\|) | O(n) | 聚合功率/带宽/连通性 |
| CEKT 迁移因子 | O(d_morph + n_x²) 离线；O(1) 在线查表 | O(n·N_kc) | d_morph=5, N_kc≤50 |
| UPM 估计/更新 | O(d_u + d_event) | O(\|U\|·d_u) | d_u=6, 用户数 \|U\| |
| FU-MPC 求解 | O(I·n·(N·n_x³ + N·n_u²·m)) | O(I·n·N·n_x) | ADMM 迭代 I=5, N=20, n=16 |
| FUCG 总体 | 单机 KTCG 主导 + O(n·k·H) | O(n·N·n_x + n·k) | 关键路径仍是各机 KT-MPC |

**实时性估计**：单机 KT-MPC 5–15ms；n=16、k=6 时 FIC 向量化检查 <5ms；CEKT 在线查表 <1ms；UPM 更新 <0.5ms。FU-MPC 采用 5 次 ADMM 且各机并行时，墙钟时间约等于「单机 KT-MPC × 5」加上一次 O(n·k) 的边界同步，目标在 50ms 内完成一个 50Hz 控制周期；若超时，降级为「FIC 先验 + 各机独立 KT-MPC」并显式标记证书为 degraded。

## 4. 正确性论证（增量更新）

### 引理 26（可达性截断的可靠性）

**陈述**：设机器人最大速度 v_max、时域 H、步长 dt、最小安全间距 d_min，令 ε_sound = d_min + 2·v_max·H·dt。若两台机器人在名义轨迹起点的距离 d_ij(0) > ε_sound，则在 [0, H·dt] 内恒有 d_ij(t) > d_min，故可安全地从邻接图 G_ε 中剔除。

**证明**：对任意 t∈[0,H·dt]，由速度有界，|d_ij(t) − d_ij(0)| ≤ ∫_0^t ||v_i(s) − v_j(s)|| ds ≤ 2·v_max·t ≤ 2·v_max·H·dt。若 d_ij(0) > d_min + 2·v_max·H·dt，则 d_ij(t) > d_min。逆否命题给出：若时域内存在 d_ij(t) < d_min，则必有 d_ij(0) ≤ ε_sound，即该对必被保留在 G_ε 中。∎

**推论**：当交互核具有紧支撑（距离 > ε_sound 时接触力/几何碰撞恒为零），G_ε 上的检查与全 O(n²) 检查等价；此时 FIC 的截断不引入漏检。

### 引理 27（硬/软分离与安全底线不变性）

**陈述**：对任意两个画像 u,u'，FUCG 的硬层判定相同，即 HardSafe(Π,u) = HardSafe(Π,u') = HardSafe(Π)；且 Exec_FUCG(u) ⊆ Exec_hard，其中 Exec_hard 为仅由硬层定义的计划集合。

**证明**：hard_gate.admits_fleet 的签名不含画像参数，其内部只调用 USMC、KTCG、FIC、CEKT，均与 u 无关，故硬层判定对 u 恒定。FUCG.admits 是硬层与软层的合取，且硬层失败时提前返回 False；软层只能在 HardSafe 为真时进一步收紧，不能把 False 反转为 True。故对任意 u，Exec_FUCG(u) = Exec_hard ∩ {Π : SoftFit(Π,u)} ⊆ Exec_hard。∎

### 引理 28（画像误差的软层界）

**陈述**：设真实画像 u、估计画像 û，软层严格度 s(·) 为 L_s-Lipschitz，且 s 只进入软层代价。则画像误差对软层接受边界的影响满足 |s(u) − s(û)| ≤ L_s·||u − û||；安全违规概率与画像误差无关。

**证明**：由 Lipschitz 性直接得到严格度差界。由引理 27，硬层与画像无关，故安全违规事件只可能由硬层判定错误引起，而硬层不接收 û，因此画像误差不改变安全违规概率；误差只改变软层代价（舒适/效率）与解释投影深度。∎

**注**：该引理成立的前提是「画像绝不进入硬层」。一旦实现中允许画像调硬层阈值（例如高信任用户跳过确认、放宽 d_min），引理 27/28 同时失效——这正是本轮最大风险的数学根源。

### 引理 29（解释投影的判定保持性）

**陈述**：投影算子 Proj_d 把完整 ExplanationReport 粗化为深度 d 的视图，满足：(a) 顶层布尔判定不变；(b) 总知识惩罚不变；(c) 单条规则的归因可能被合并，但合并组的惩罚和等于组内规则惩罚之和。

**证明**：Proj_d 定义为对解释树的保结构商映射：叶子布尔值与惩罚值原样保留，仅把深度超过 d 的子树折叠为其父节点，并把被折叠叶子的惩罚相加后挂到父节点。商映射不改变叶子的值，也不改变求和结果，故 (a)(b)(c) 成立。∎

### 定理（FUCG 的机群级可靠性）

**陈述**：若 `FUCG.admits(Π, sensor, u) = True`，则：
1. 每台机器人满足其单机 KTCG 的全部硬约束；
2. 所有在时域内可能进入 d_min 的机器人对都满足 InterCert；
3. 机群聚合不变式 FleetInv 成立；
4. 画像 u 没有放宽任何硬层阈值。

**证明**：由 FUCG.admits 的四步合取逐项得到。步骤 1 对应每机 KTCG；步骤 2 由 FIC 给出，其中邻接图由 ε_sound 构造，引理 26 保证可能违规的对不会被截断，且度数截断处额外做了「被截断邻居若 d<d_min 则失败」的兜底；步骤 3 由 check_fleet_invariants 给出；步骤 4 由 UCCG 的硬层签名不含 u、引理 27 给出。∎

## 5. 实验设计（多机评测 + 用户画像）

> 说明：以下数值均为**验收目标/预期区间**，不是已完成的实验结果；本轮只给出可复现的实验协议与判定标准。

### 5.1 多机评测（仿真）

**平台**：N∈{3,8,16} 台异构双足机器人，腿长 0.6–0.9m、质量 20–60kg、关节限位与足底面积各异；共享 10m×10m 工作区，地形含平地/湿滑/碎石；机间通信有 50–200ms 抖动。

**对照**：
- B1：独立 KTCG（单机证书的简单合取，无交互项）；
- B2：全对 O(n²) 交互检查（金标准，仅小 n 可跑）；
- B3：FIC（ε_sound 截断 + 度数上限）；
- B4：FIC 去掉 FleetInv；
- B5：FIC + CEKT（本文完整硬层）。

**指标**：
- 假接受率 FAR：不安全计划被准入的比例（越低越好，主指标）；
- 假拒绝率 FRR；
- 最小机间距违反次数/千步；
- 死锁率与任务完成时间；
- 单步评测时延随 n 的缩放；
- 跨具身冷启动成功率（CEKT 开启 vs 关闭）。

**预期/验收目标**：

| 指标 | B1 独立 | B3 FIC | B5 FIC+CEKT | 判定 |
|---|---|---|---|---|
| FAR（n=8） | 基线（高） | ≤ B1 的 1/5 | ≤ B1 的 1/6 | B5 显著优于 B1 |
| 最小间距违反 | 常见 | 0（紧支撑） | 0 | 硬指标 |
| n=16 单步时延 | — | < 50ms | < 50ms | 实时 |
| 冷启动成功率 | 基线 | — | +≥15 个百分点 | CEKT 有效 |
| 迁移规则不安全率 | — | — | < 1% | ν 门控有效 |

**消融**：ε ∈ {0.25, 0.5, 1.0}·ε_sound、k_max ∈ {4,6,8}、紧支撑 vs 非紧支撑耦合（后者应触发 FleetInv 兜底）、有无度数截断兜底（用于验证引理 26 的必要性）。

### 5.2 用户画像（人机闭环）

**被试**：K=24–36 名操作员，按专业度（新手/专家）与风险偏好（问卷测量）分层；每人间隔重复测量以估计 Σ_u。

**条件（被试内/被试间混合）**：
- E1：固定解释（统一深度 d=3）+ 固定软层严格度；
- E2：画像投影解释（d_u）+ 固定软层；
- E3：画像投影解释 + 画像软层严格度；
- E4：E3 + 显式「硬层不可调」提示与审计视图。

**注入测试**：在部分试次中，向界面呈现一个**硬层不合格但外观正常**的计划，并标注为「已认证」（用于测自动化偏信）。正确行为是拒绝；由于硬层与画像无关，E1–E4 的硬层接受率都应为 0。

**指标**：信任校准（自报信任与系统真实可靠性的差）、自动化偏信率（对注入不安全计划的接受率）、理解测验得分、NASA-TLX 工作负荷、接管适当率、满意度。

**预期/验收目标**：

| 指标 | E1 | E3/E4 | 判定 |
|---|---|---|---|
| 注入不安全计划接受率 | 0（若硬层正确） | 0 | 安全底线不被画像侵蚀 |
| 理解测验 | 基线 | +≥20% | 投影解释有效 |
| 工作负荷（TLX） | 基线 | −≥15% | 画像减负 |
| 信任校准误差 | 基线 | 降低 | 不靠讨好提升信任 |
| 软层满意度 | 基线 | 提升 | 个性化仅在软层生效 |

**分析**：混合效应模型，固定效应为条件与专业度，随机效应为被试；预先注册主要终点（FAR、注入接受率、理解度），其余为探索性。若 E3/E4 的注入接受率 > 0，视为实现违反硬/软分离，实验直接判失败（而不是调参）。

## 7. 本轮最大风险（最终确认）

**一句话**：**画像相对化的安全底线侵蚀**——只要实现中允许画像参与硬层阈值（哪怕只是「高信任用户可跳过确认」），误分类或对抗性画像就能把不安全计划认证成「符合该用户偏好」，而机群交互图会把这一单点错误放大为编队级事故；它比迁移负外部性更危险，因为错误被包装成了「个性化服务」。
