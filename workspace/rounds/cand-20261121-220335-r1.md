# 第 1 轮（UniBot 线 · 本轮灵感：「抓取规划」×「云端协同」）

> **基线承接**：本轮沿用状态文件中已确立的 UniBot 基线（定义 U1–U12 / 引理 L1–L7 / 实验 E601–E618）与其三条结论——T1 终态成功是唯一计分货币、T2 通用能力是近正交技能向量、T3 断点在最后的对齐/插入/释放。不重复陈述旧内容；**新增编号从 U13 / L8 / E619 起**。上一轮的"抓握确认（GraspVerify）"是**事后**判断"抓住没有"，本轮把它向上游推进为**事前**规划"该怎么抓、抓住后还能不能完成任务"。

## 0. 一句话直觉

**抓取规划**：在接触之前就把"抓哪里、以什么姿态抓、抓完还能不能完成下游动作"算清楚——因为单自由度夹爪的可行抓取集合既稀疏又和任务强耦合，抓法选错，后面每一步都在还债。
**云端协同**：抓取规划"重而慢"、伺服执行"轻而快"，把前者放到云端异步算、后者留在边端同步跑；再用**物体坐标系锚定**让慢计划对延迟免疫——计划锚在物体上，物体动，执行器每步重新估计物体位姿即可，计划本身不随时间腐烂。

## 1. 两个灵感的第一性原理

### 灵感 A ·「抓取规划」→ 抓取不是反射，是任务条件化的前瞻决策

第一性原理：上一轮已论证"抓住没有"是隐变量；但更上游的失败是"抓法从第一步就选错了"。三条硬约束把它变成规划问题：

1. **可行集稀疏**：Dex1 只有 1 维开合（5.5→0），没有手指关节、没有触觉。拧瓶盖、插钥匙、捏细线这类需要指内操作或包络的抓法在物理上不可行。可行抓取不是连续流形，而是一组**离散、稀疏、带硬约束**的候选。
2. **任务耦合**：很多任务要求抓取后**保留一个自由度**——插网线要露出插头轴线、插钥匙要露出齿向、开瓶盖要露出旋转轴、取电池要避免夹住触点面。一个"抬得起来"的抓法，可能恰好"插不进去"。
3. **误差放大**：抓取位姿的 5° 偏差，经过 20 cm 的搬运与插入，会放大成末端 1–2 cm 的错位；而插入容差常常只有几毫米。抓取规划是整条误差链的**第一级增益**。

因此抓取规划的目标函数不应是 `P(lift | grasp)`，而应是 `P(downstream success | grasp plan)`。这把抓取从"末端执行器的一个动作"提升为"整条任务链的约束"。

**推论**：需要 (a) 任务条件化的抓取候选生成；(b) 1-DOF 可行性硬过滤；(c) 抓取后运动/接触的可达性预测；(d) 抓取计划与下游原语（插/拧/放/推）之间的显式接口。

### 灵感 B ·「云端协同」→ 规划与执行的时间尺度天然分离

第一性原理：抓取规划的计算量（多视角重建、候选采样、碰撞检查、稳定性/任务兼容性打分）比一次 VLA 前向大 1–2 个数量级，但它的输出**变化慢**；伺服执行的计算量小，却要求 10–30 Hz 的**低延迟**。而评测接口是同步 request-response，且有 per-step 延迟预算（官方参考 WLA <105 ms）。由此得到一条硬结论：

- 把抓取规划放在**同步路径**上 ⇒ 每步延迟 150–600 ms，必然超预算、必然被"延迟波动"可信度口径扣分；
- 把抓取规划完全**离线固化** ⇒ 无法吸收 5 类泛化场景带来的测试时分布偏移；
- 唯一可行解是**异步云规划 + 同步边执行 + 计划有效期契约**：云端在后台持续产出计划，边端只消费"最新且未失效"的计划，规划永不在关键路径上。

**推论**：需要 (a) 非阻塞、版本化的计划总线；(b) 计划的时间戳/版本/失效条件；(c) 计划切换的代价模型；(d) 多机器人共享后端时的并发与状态隔离。

### 合成

`抓取规划（任务条件化 + 1-DOF 可行性）× 云端协同（异步 + 物体锚定 + 验证器优先）`
⇒ 一个**云边分层抓取系统**：
**云规划层（慢：生成-过滤-打分）→ 计划总线（异步：版本-有效期-切换）→ 边执行层（快：跟踪-伺服-失效检测）→ 计划记忆层（机队：检索-复用-合规分级）**，
外加工程层（非阻塞、并发隔离、延迟/切换/降级可审计）。

## 2. 本轮对"抓取规划"瓶颈的量化再分析

沿用 teaser 榜结构（8 模型 × 32 任务，n=256；数据源与保留意见见上一轮 §10），本轮新增三类测算：

| 观测 | 数值 | 对策略的含义 |
|---|---|---|
| 最难 6 任务均值 vs 最好任务 | 21.35 vs 30.3，gap = **8.95** | 若抓取规划补上这个 gap 的 f 比例，整体增益 ≈ **+1.68·f 分**（f=0.5→+0.84）；是必要但不充分的杠杆 |
| VLA 前向 vs 云端规划延迟 | 前向 35–70 ms；规划工程估计 150–600 ms（2–10×） | **同步规划必超 105 ms 预算** ⇒ 异步不是优化，是可行性前提 |
| best-of-K 抓取候选（离线模拟，200k trials） | K=1: 0.50；K=8, 验证器噪声 σ=1: **0.706**（+41% 相对）；σ=2: 0.632 | 即使排序不完美，"多采样 + 验证"仍有显著增益 |
| 物体锚定 vs 世界锚定（计划龄 5 步，容差 10 mm） | 世界锚定 **80.2%** 超差；物体锚定 **0%** 超差（残差 3.1 mm） | **物体坐标系锚定是异步计划的关键使能技术** |
| 算力分配（固定 σ=1，K 从易态挪到难态） | 平均成功变化 **< 0.002** | 简单加采样几乎无用；真正的杠杆是**降低验证器噪声**（K=8: σ=1→0.706, σ=0.5→0.761, σ=0→0.789） |
| 机队计划记忆（N=8, 单机成功率 q=0.30） | **60.7%** episode 可命中"之前某台机器人成功过的计划" | 潜在红利大，但属**合规灰区**（见 §7），默认关闭 |

**本轮结论（可执行）**：

- **G1 抓取规划是误差链第一级**：必须用"下游成功率"而非"抓取成功率"做目标，否则优化了一个错误代理。
- **G2 物体锚定解耦延迟**：异步计划的正确性不取决于计划多新，而取决于物体位姿跟踪多准；这直接把问题从"规划延迟"转成"跟踪置信度"。
- **G3 验证器 > 采样数**：在固定算力下，提升验证器排序质量比增加候选数更划算（负结果也有价值）。
- **G4 云边分层是接口约束下的唯一形态**：单 API、单 checkpoint 不变，内部用异步计划总线把慢规划隔离出关键路径。

## 3. 研究问题（轮次版）

- **Q1（任务条件化抓取）**：在 1 维开合、无触觉的约束下，如何把"下游兼容"编码成可学习的抓取可行性/打分函数？它与"抓得稳"在多大程度上冲突？
- **Q2（异步计划的正确性）**：物体锚定计划在多大计划龄、多大物体运动、多大跟踪误差下仍然有效？失效如何被**可观测地**检测？
- **Q3（边端伺服）**：如何用腕部视觉伺服去跟踪一个"可能已过时"的抓取计划，并在计划失效时安全退化而不把可救失败变成硬失败？
- **Q4（云端算力）**：在固定延迟预算下，算力应花在"更多候选"还是"更强验证器"？能否用 value-of-information 在线分配，且收益可被真机 A/B 证实？
- **Q5（机队协同的合规边界）**：跨机器人计划缓存/统计共享是否构成"使用评测数据"？最严格的合规形态（episode 内记忆 + 只读几何先验）还剩多少红利？

## 4. 设计原则

- **P1 单一计分货币**：所有改动必须能写成"提升终态成功率"的因果链；抓取计划的好坏用**下游**成功率度量。
- **P2 计划与执行分离**：慢规划（云端、异步、可重算）与快执行（边端、同步、硬实时）解耦；规划永不在关键路径。
- **P3 物体锚定**：计划定义在物体坐标系；执行器每步重估物体位姿。计划龄不直接转化为位姿误差。
- **P4 计划可失效**：任何计划都带有效期与失效判据；失效即退化，不"带病执行"。
- **P5 验证器优先于生成器**：固定算力先投验证器排序质量，再投候选数量。
- **P6 合规分级**：机队记忆默认关闭；跨 episode/跨机器人共享须书面确认，并常备 no-memory 对照。
- **P7 单模型、单 checkpoint、单 API**：内部云边拆分不改变对外暴露的一个策略服务；云规划器是同一部署内的后台组件，不是第二个被评测的策略。

## 5. 系统总览：UniBot-GRACE

> **GRACE = Grasp Reasoning with Asynchronous Cloud-Edge**（异步云边抓取推理）。

```
        ┌──────────────────────────── 云端（慢，1–5 Hz，非关键路径）────────────────────────────┐
        │  多视角观测 ─► 物体/部件分割 ─► 任务条件化候选生成 ─► 1-DOF 可行性过滤 ─► 验证器打分      │
        │                                                   │                                   │
        │                              物体锚定计划 p=(T_O^g, w, h, s, κ)                        │
        └───────────────────────────────────────────────────┼───────────────────────────────────┘
                                                            ▼
        ┌──────────────────── 计划总线 PlanBus（版本化 / 有效期 / 切换代价 / 审计）───────────────┐
        │  状态机: IDLE→REQUESTED→PLANNING→READY→COMMITTED→(STALE|INVALID)→IDLE                    │
        │  规则: 只有 READY 且 Δ≤H 且 safe-to-switch 且 benefit>C_switch 才提交                     │
        └───────────────────────────────────────────────────┬───────────────────────────────────┘
                                                            ▼
        ┌──────────────────────────── 边端（快，10–30 Hz，关键路径）──────────────────────────────┐
        │  物体位姿跟踪 T_W^O + 置信度 c_t ─► 腕部视觉伺服 ─► 抓取/插入/放置原语 ─► 失效检测/退化    │
        └───────────────────────────────────────────────────┬───────────────────────────────────┘
                                                            ▼
        ┌──────────────────────── 计划记忆 FleetPlanMemory（默认关；合规分级）────────────────────┐
        │  (物体描述子, 任务, 计划, 结果) 检索；只读复用；no-memory 对照常备                        │
        └─────────────────────────────────────────────────────────────────────────────────────────┘
```

**关键设计点**：

1. **任务条件化候选生成**：从语言指令 `ℓ` 解析任务类型（pick/place/insert/rotate/pour），据此选择候选生成器的接触先验（顶抓 / 侧抓 / 轴对齐抓 / 边缘抓）。
2. **1-DOF 可行性硬过滤**：宽度匹配、反对跖接触、接近方向无碰撞、抓后任务自由度未被锁死。硬过滤先于打分，避免验证器给物理不可行的计划打高分。
3. **物体锚定**：计划存 `T_O^g` 而非 `T_W^g`。执行器每步输出 `T_W^g = T_W^O · T_O^g`，因此计划龄 Δ 只影响 `T_W^O` 的估计，不影响计划本身。
4. **验证器优先**：云端预算先用于"把候选排序做准"（更强的几何/VLM 验证器、校准），再用于"多采样"。
5. **边端失效检测**：残差 `r_t = ‖T_W^g − T̂_W^O·T_O^g‖`、跟踪置信度 `c_t`、物体视觉变化三者联合判定；任一越界即退化。
6. **机队记忆默认关**：只保留 episode 内计划缓存；跨机器人复用作为"合规确认后的增益项"，不进入 MVP。

## 6. 最小可提交闭环（MVP）与退化链

**MVP = IP-09（云抓取规划）+ IP-10（边端伺服与失效检测）+ IP-11（异步计划总线）+ 通用 VLA 基线 + IP-14（代理评测）**。
理由：IP-09 决定抓取质量上限，IP-10/IP-11 保证它能真的跑在延迟预算内，IP-14 提供不依赖真机的迭代标尺。IP-12（验证器算力分配）作为 IP-09 的内部模块先做离线验证；IP-13（机队记忆）默认关闭。

**严格退化链（任一环节不可用 ⇒ 行为回退而非漂移）**：

- **D0 完整异步**：云规划 + 物体锚定 + 边端伺服。
- **D1 跟踪退化**：物体位姿跟踪置信度低 ⇒ 退回**世界锚定 + 短计划龄门控**（只在 Δ≤2 时用计划）。
- **D2 验证器不可用**：退回几何启发式排序（反对跖 + 碰撞 + 宽度）。
- **D3 计划总线故障**：退回**同步单次规划 + 固定 chunk**（保证能跑）。
- **D4 全链路失效**：退回**纯基线策略**（永远保留一份能跑通、可信度合规的最小提交）。

## 8. 预期贡献（可验收）

1. **任务条件化抓取规划器**：给出 1-DOF 下的"下游兼容"可行性定义与打分器；验收指标是**下游任务成功率**，而非抓取成功率。
2. **物体锚定异步计划的形式化**：给出计划龄-成功率曲线与失效检测 ROC，证明"延迟免疫"的边界条件（而不是无条件宣称）。
3. **云边计划总线**：非阻塞、版本化、可审计；验收 p99 延迟不因规划而退化，降级次数与切换频率可导出。
4. **验证器优先的算力分配结论**：包含一个诚实的负结果——简单把采样从易态挪到难态收益 <0.002，真正的杠杆是验证器噪声。
5. **机队计划记忆的合规分级与对照实验**：把"云端协同"的红利与合规风险同时量化。
6. **GRACE-Bench 代理评测**：抓取计划级指标（计划龄、可行性、下游六因子）与真机相关性标定，成为后续轮次的公共标尺。

## 9. 本轮最大风险

**一句话**：本轮把赌注压在"任务条件化抓取规划 + 物体锚定异步执行"上，而最大风险是——**物体位姿跟踪在未见物体、遮挡、反光、透明物体上的漂移会让"物体锚定"悄悄退化为"错误锚定"**：计划本身没有错，却被贴到了一个漂移的坐标系上，而且异步链路让这种错误比同步方案更晚才被发现；一旦跟踪置信度的校准不准，"延迟免疫"的前提就反转成"延迟放大的错误"。

## 10. 下一轮迭代计划（深化与修剪，不推倒重来）

- **深化**：把 IP-10 的失效检测从"残差阈值"升级为"跟踪置信度 + 计划龄 + 物体视觉变化"的三通道校准器；把 IP-09 的任务条件化打分器与上一轮 IP-06 的六因子分解对齐（抓取规划直接对 grasp/align/insert 三因子负责）。

- **保留项**：IP-09（抓取质量上限）、IP-10（延迟与安全）、IP-11（工程确定性）、IP-14（标尺）在任何情况下不砍。

## 0. 本轮结论摘要

**一句话路线**：把"抓取规划 × 云端协同"编译成一条**云边分层抓取栈**——
**云规划层**（任务条件化候选 → 1-DOF 可行性过滤 → 物体锚定计划 → 验证器打分）→ **计划总线**（版本化 / 有效期 / 切换代价 / 审计）→ **边执行层**（物体位姿跟踪 → 腕部伺服 → 失效检测 / 退化）→ **计划记忆层**（机队检索，默认关，合规分级）。

**为什么是这个组合（四条依据）**：

| 证据 | 数值 | 推出的设计 |
|---|---|---|
| 最难 6 任务均值 21.35 vs 最好任务 30.3，gap 8.95 | 抓取/插入/旋转是系统性洼地 | 抓取规划补 gap 的 f ⇒ 整体 +1.68·f 分；必要但不充分 → IP-09 |
| VLA 前向 35–70 ms；云端规划工程估计 150–600 ms | 规划比前向慢 2–10×，远超 105 ms 预算 | **异步而非同步** → IP-11 |
| 离线模拟：世界锚定计划龄 5 步时 80.2% 超差；物体锚定 0% | 延迟正确性的关键在"锚在哪" | **物体坐标系锚定** → IP-09/IP-10 |
| 离线模拟：K=8 时 σ=1→0.706，σ=0→0.789；简单挪采样收益 <0.002 | 验证器质量 >> 采样数量 | **验证器优先** → IP-12 |

**合规红线（承接 P5/P6）**：单 checkpoint、单 API；云规划器是同一部署内的后台组件，不是第二个被评测的策略；机队跨机器人记忆默认关闭，需书面确认；不做"读题即硬编码"的分支。

## 2. 创新点详述

### IP-09 · CloudGrasp 任务条件化云抓取规划器（P0）

- **动机**：上一轮证明"抓住没有"是隐变量；但更上游的失败是"抓法选错"。单自由度夹爪的可行抓取集合离散且稀疏，且插入/旋转类任务要求抓后保留特定自由度（插头轴线、钥匙齿向、瓶盖旋转轴）。teaser 榜最难 6 任务（均值 21.35）几乎全是插入/旋转/细粒度摆放，正是"抓法与下游不兼容"的高发区。
- **与现有方案的差异**：现有 VLA 把抓取当作动作块的一部分端到端输出，抓取位姿是隐式的、无硬约束、无下游兼容性打分。我们把它显式化为**三阶段**：①任务条件化候选生成（按语言解析 pick/insert/rotate/pour，选接触先验）；②1-DOF 可行性硬过滤（宽度、反对跖、接近无碰撞、抓后自由度未锁死）；③验证器打分（几何 + VLM，目标是 `P(downstream success | plan)`）。
- **技术可行性**：中–高。输入是 4 路相机 + 本体状态，输出是 `SE(3)` 抓取计划；物体/部件分割可用现成 2D/3D 模型；1-DOF 过滤是几何规则；验证器可用小 VLM + 几何特征。全部可在官方数据上离线训练/回放。
- **所需资源**：数据 = 官方 32 数据集 + 自动伪标；算力 = 云端 1–2 张 A100（分割 + 采样 + 验证器），训练单卡数天。
- **落地步骤**：①统一下载/解码管线（复用上一轮 IP-06）；②语言→任务类型解析器（规则 + 小分类器）；③任务条件化候选生成器（每类接触先验各一个采样头）；④1-DOF 可行性过滤（硬规则）；⑤验证器训练与校准（可靠性图）；⑥object-anchored 计划格式与序列化；⑦离线回放（E619）。
- **风险**：①分割/位姿在未见物体上漂移 ⇒ 用跟踪置信度门控 + 退化到世界锚定短计划；②验证器与下游成功相关性不足 ⇒ E619/E620 先行，<0.3 则退回几何启发式；③候选生成漏掉可行抓法 ⇒ 保留"基线 VLA 直接抓"作为并行候选，不把鸡蛋放一个篮子。

### IP-10 · EdgeServo 边端抓取伺服 + 失效检测（P0）

- **动机**：计划可能过时，执行不能"照本宣科"。边端必须在 10–30 Hz 内完成：物体位姿跟踪、把物体锚定计划换算成世界系目标、腕部视觉伺服、抓取/插入/放置原语执行，以及**失效检测**。
- **与现有方案的差异**：现有 chunk 执行是开环的（上一轮 IP-03 做的是 chunk 缝合，不是计划跟踪）。我们把执行器变成**计划跟踪器**：目标是 `T_W^g = T_W^O · T_O^g`，每步重估 `T_W^O`；计划龄只影响跟踪误差，不影响计划本身。
- **技术可行性**：高。物体位姿跟踪可用腕部/头部帧 + 已知物体模型或 6D pose 估计；伺服用现有视觉伺服；失效检测是阈值/统计规则。
- **所需资源**：接口 = 无新增字段（仍是 `get_action`）；算力 = 边端 ≤10 ms/步（跟踪 + 伺服），与主策略共享 GPU/CPU 但资源隔离。
- **落地步骤**：①实现 `T_O^g → T_W^g` 的坐标链；②物体位姿跟踪器 + 置信度；③腕部视觉伺服（pre-grasp → grasp → lift 分段）；④三通道失效检测（残差 `r_t`、置信度 `c_t`、视觉变化 `ΔI_t`）；⑤退化执行（D1/D2/D3）；⑥真机 A/B（E622–E626）。
- **风险**：①跟踪漂移 ⇒ 这正是本轮最大风险，用置信度门控 + 短计划龄 + 世界锚定回退；②伺服与策略动作空间冲突 ⇒ 伺服只作用于接近/对齐相位，抓取后交回策略；③失效检测误报导致频繁退化 ⇒ 阈值用 ROC 选，且退化是"降级"不是"中断"。

### IP-11 · PlanBus 异步计划总线 + 时序契约（P0）

- **动机**：官方采集 per-step 延迟及其波动并可能据此评估可信度。若云端规划与边端执行共享同步路径，延迟尖峰不可避免。必须从架构上保证"规划永不在关键路径"。
- **与现有方案的差异**：常见部署是"一个大模型同步出动作"；我们把系统拆成**后台规划进程 + 前台执行进程 + 版本化计划总线**，前台只做原子读，永不等待后台。
- **技术可行性**：高（系统工程）。关键是指标：p99、计划龄分布、切换频率、降级次数。
- **所需资源**：接口 = 官方 client/server；算力 = 极小；数据 = 无（可用回放做连续性自检）。
- **落地步骤**：①定义计划消息格式 `(p, κ, t_plan, H, s, h)`；②实现状态机 `IDLE→REQUESTED→PLANNING→READY→COMMITTED→(STALE|INVALID)→IDLE`；③提交规则（安全点 + 有效期 + 切换代价）；④资源隔离（独立进程/线程 + 配额，避免 GPU 争用）；⑤埋点与审计看板（p50/p99、计划龄、切换、降级）；⑥N 端口 × 8 h 并发压测。
- **风险**：①共享 GPU 导致"逻辑隔离但物理争用" ⇒ 用配额/优先级/独立卡；②计划频繁切换引入抖动 ⇒ 切换代价模型 + 最小驻留时间；③状态跨端口串扰 ⇒ 每端口独立 session + 压测（承接上一轮 IP-08）。

### IP-12 · PlanVerifier 抓取计划验证器 + 算力分配（P0）

- **动机**：离线模拟给出一个**负结果**：在固定验证器噪声 σ=1 下，把采样预算从"易态"挪到"难态"的平均收益 <0.002；而把 σ 从 1 降到 0.5，K=8 的成功从 0.706 升到 0.761。⇒ 算力的真正杠杆是**验证器排序质量**，不是候选数量。
- **与现有方案的差异**：多数 best-of-K 方案把预算花在"多生成"；我们先花在"多判断"（几何验证 + VLM 验证 + 校准），再决定 K。
- **技术可行性**：中–高。验证器 = 几何特征（反对跖、接触面积、碰撞、可达性）+ 小 VLM（任务兼容性）+ 校准层。
- **所需资源**：数据 = 官方数据 + 伪标；算力 = 小（验证器比生成器便宜）。
- **落地步骤**：①定义验证器输入（计划 + 多视角局部观测 + 任务类型）；②训练/蒸馏；③校准（可靠性图、温度缩放）；④VOI 分配策略（按状态不确定性 × 下游影响给 K）；⑤对比 uniform vs VOI（E629）；⑥把负结果写入预注册。
- **风险**：①验证器在 OOD 上过度自信 ⇒ 校准 + 保守阈值；②VLM 验证延迟高 ⇒ 只在云端异步跑，不进关键路径；③"验证器偏好"与真机成功不一致 ⇒ E619/E620 标定。

### IP-13 · FleetPlanMemory 机队计划记忆（P1，默认关）

- **动机**：评测在 N 台真机上随机顺序执行；若计划可跨机器人复用，早期成功计划可成为后期先验。离线模拟：N=8、单机成功率 q=0.30 时，60.7% 的 episode 可命中"之前某台成功过的计划"。
- **与现有方案的差异**：把"云端协同"从"单机云边"扩展到"机队级知识共享"，但**先合规后收益**。
- **技术可行性**：中。检索用物体描述子 + 任务 token；存储是只读 KV/向量库。
- **所需资源**：接口 = 共享后端已有；算力 = 极小；数据 = 运行期轨迹。
- **落地步骤**：①定义 `(d_obj, z_task, p, outcome)` 记录；②检索与相似度阈值；③**默认关闭**，提供 no-memory 对照；④向组委会书面确认；⑤确认后做 E631/E632。
- **风险**：①合规（最高）⇒ 分级 + 书面确认 + 默认关；②分布偏移导致错误复用 ⇒ 相似度阈值 + 只读不改权重；③"评测期学习"质疑 ⇒ 保留完整 no-memory 提交形态。

### IP-14 · GRACE-Bench 抓取规划代理评测（P0）

- **动机**：真机时段稀缺，teaser 榜非终稿；需要不依赖真机的标尺来迭代"计划龄/可行性/验证器"。
- **与现有方案的差异**：上一轮 IP-06 是任务级六因子；本轮增加**计划级**指标：计划龄-成功率曲线、可行性过滤召回、object-anchored vs world-anchored 回放、验证器校准。
- **技术可行性**：中–高。官方数据可回放；object-anchored 计划可从数据中的物体位姿与 EE 轨迹反推。
- **所需资源**：数据 = 官方 32 数据集；算力 = 中（回放 + 小评估器）。
- **落地步骤**：①从数据反推物体相对 EE 的抓取计划；②构造计划龄扰动与跟踪噪声；③回放 object/world 锚定；④验证器校准评估；⑤与真机 A/B 标定相关性（E635）。
- **风险**：①回放与真机差距大 ⇒ 预注册 |r|<0.3 即剪枝；②物体位姿标注噪声 ⇒ 双标注器一致性检查。

## 3. 符号与定义（U13–U24）

| 符号 | 含义 |
|---|---|
| `o_t` | 时刻 t 的观测（4 路相机 + 本体 + 语言） |
| `ℓ` | 语言指令 |
| `O` | 目标物体坐标系 |
| `p` | 抓取计划（物体锚定） |
| `T_O^g` | 抓取帧在物体系下的位姿 ∈ SE(3) |
| `w` | 夹爪目标开合 ∈ [w_min, w_max] |
| `h` | 功能标签（axis_free_z / top_down / side / edge 等） |
| `s` | 计划分数 ∈ [0,1] |
| `κ` | 计划版本号 / 时间戳 |
| `Δ` | 计划龄 = t − t_plan |
| `H` | 计划有效期（动态） |
| `T_W^O` | 物体在世界系的位姿估计 |
| `c_t` | 物体位姿跟踪置信度 ∈ [0,1] |
| `r_t` | 计划执行残差 |
| `K` | 云端候选采样数 |
| `σ` | 验证器排序噪声（越小越准） |
| `B` | 云端算力预算 |
| `M` | 机队计划记忆 |
| `D0–D4` | 退化等级 |

**定义 U13（物体锚定抓取计划）** `p = (T_O^g, w, h, s, κ)`：抓取位姿定义在物体坐标系 `O` 下，而非世界系；执行时换算 `T_W^g = T_W^O · T_O^g`。这样计划龄 `Δ` 不直接改变计划，只影响 `T_W^O` 的估计误差。

**定义 U14（1-DOF 可行性）** `F(p, o, ℓ) = 1` 当且仅当：①`w` 与物体宽度匹配且 ∈ [w_min,w_max]；②预测接触对近似反对跖；③接近方向无碰撞；④任务兼容——抓后任务关键自由度未被锁死（插入类要求 `|a_ins · n_grip| ≥ cos θ_max`，旋转类要求旋转轴不被夹持面遮挡）。`F=0` 的计划不进入打分。

**定义 U15（计划有效期）** `H = min(H_max, δ_track / (v_obj + ε))`，其中 `δ_track` 为可容忍位姿误差，`v_obj` 为物体估计速度。计划仅在 `Δ ≤ H` 且 `c_t ≥ c_min` 时可用。

**定义 U16（物体位姿跟踪）** `T̂_W^O(t)` 与置信度 `c_t`；跟踪误差上界记为 `δ_o(c_t)`，随 `c_t` 单调不增。

**定义 U17（计划总线状态机）** `IDLE → REQUESTED → PLANNING → READY → COMMITTED → (STALE | INVALID) → IDLE`。只有 `READY` 且版本 `κ` 大于当前、`Δ ≤ H`、处于安全切换点、且净收益为正时才可 `COMMITTED`。

**定义 U18（切换代价与净收益）** 从计划 `p` 切到 `p'` 的净收益 `ΔU = [s(p') − s(p)] · P(reach pre-grasp | safe) − C_switch`；仅当 `ΔU > 0` 且 `safe-to-switch` 才切换。

**定义 U19（验证器）** `v(p, o, ℓ) ∈ [0,1]`，经校准使 `P(success | v)` 单调；以可靠性图与 AUROC 验收。

**定义 U20（算力分配）** 策略 `μ: state → (K, m)`，`K` 为候选数、`m` 为验证器调用次数，约束 `E[cost(μ)] ≤ B`；目标最大化 `E[success]`。VOI 指数 `VI(s) = E_{v}[max_j v(p_j)] − max_j E[v(p_j)]`。

**定义 U21（机队计划记忆）** `M = {(d_obj, z_task, p, outcome)}`，检索按 `d_obj` 与 `z_task` 相似度排序，返回计划与成功统计；**评测期只读**，不更新权重。

**定义 U22（失效检测）** `invalid_t = 1` 若 `r_t > ρ` 或 `c_t < c_min` 或 `ΔI_t > ι`（物体视觉变化超阈）；否则 0。

**定义 U23（退化等级）** `D0` 完整异步；`D1` 世界锚定 + 短计划龄；`D2` 同步单次规划；`D3` 固定 chunk 基线；`D4` 纯基线策略。

**定义 U24（延迟预算）** 边端每步预算 `τ_e`（目标 p99 ≤105 ms），云端规划截止 `τ_c`（不进入关键路径）；总 p99 由 `τ_e + jitter` 决定，`τ_c` 不影响。

## 4. 关键算法骨架

```python
# ===== 云端：异步抓取规划（非关键路径，1–5 Hz） =====
class CloudGraspPlanner:
    def __init__(self, seg, sampler, verifier, budget=1.0):
        self.seg, self.sampler, self.verifier, self.budget = seg, sampler, verifier, budget

    def plan(self, obs, language, memory=None):
        # 1) 任务条件化：语言 -> 任务类型 -> 接触先验
        task = parse_task(language)                 # pick/place/insert/rotate/pour
        # 2) 分割 + 物体坐标系 O
        obj_mask, T_W_O = self.seg(obs, task)
        # 3) 候选生成（任务条件化采样头）
        cands = self.sampler(task, obs, T_W_O, K=self.alloc_k(obs, task))
        # 4) 1-DOF 硬过滤（不可行不进打分）
        cands = [p for p in cands if feasible_1dof(p, obs, task)]
        if memory is not None:                      # IP-13，默认 None
            cands = merge_retrieved(cands, memory.query(T_W_O, task))
        # 5) 验证器优先：先排序准，再决定要不要加采样
        scored = [(p, self.verifier.score(p, obs, task)) for p in cands]
        p_star, s_star = max(scored, key=lambda x: x[1])
        return GraspPlan(T_O_g=p_star.T_O_g, w=p_star.w, h=task,
                         s=s_star, kappa=next_version())

    def alloc_k(self, obs, task):
        # VOI：高不确定性 × 高下游影响 -> 多采；否则少采
        u = uncertainty(obs, task)
        return clip(int(2 + 6 * u), 2, 8)


# ===== 计划总线：版本化、有效期、切换代价（边端只读，永不阻塞） =====
class PlanBus:
    def __init__(self):
        self.latest = None          # atomic read
        self.version = 0

    def publish(self, p, now):
        if p is None or not feasible(p):
            return
        self.version += 1
        p.kappa = self.version
        p.t_plan = now
        self.latest = p             # 原子替换

    def read(self):
        return self.latest          # 边端不等待、不锁


# ===== 边端：抓取伺服 + 失效检测 + 安全退化（关键路径） =====
class EdgeServo:
    def __init__(self, tracker, servo, bus, c_min=0.6, rho=0.01):
        self.tracker, self.servo, self.bus = tracker, servo, bus
        self.c_min, self.rho = c_min, rho
        self.session = {}

    def act(self, obs, port):
        s = self.session.setdefault(port, Session())
        t0 = time.perf_counter()
        p = self.bus.read()
        if p is None or not self.valid(p, obs, s):
            return self.degrade(obs, s)                 # D1–D4
        T_W_O, c = self.tracker(obs)
        if c < self.c_min:
            return self.degrade(obs, s)                 # 跟踪退化
        T_W_g = T_W_O @ p.T_O_g
        a = self.servo(obs, T_W_g, p, s.phase)          # 腕部视觉伺服
        s.last_p = p
        return self.pack(a, budget_ok=(time.perf_counter()-t0)*1000 < 105)

    def valid(self, p, obs, s):
        age = obs.t - p.t_plan
        H = min(H_MAX, self.tracker.delta_track / (self.tracker.v_obj(obs) + 1e-6))
        r = self.tracker.residual(obs, p)
        return (age <= H) and (r <= self.rho)

    def degrade(self, obs, s):
        # D1 世界锚定短计划 -> D2 同步单次规划 -> D3 固定 chunk -> D4 纯基线
        for level in (D1, D2, D3, D4):
            a = self.try_level(level, obs, s)
            if a is not None:
                s.audit.mark_degraded(level)
                return a
        raise RuntimeError("baseline safety net missing")
```

## 5. 推导（引理 L8–L14）

**引理 L8（物体锚定的延迟不变性）** 若计划存于物体系 `T_O^g`，执行时 `T_W^g = T̂_W^O · T_O^g`，且跟踪误差 `‖T̂_W^O − T_W^O‖ ≤ δ_o`，则抓取位姿误差 `≤ δ_o + δ_servo`，**与计划龄 Δ 无关**；对比世界锚定计划的误差随 `‖v_obj‖·Δ` 增长。证明：误差只通过 `T̂_W^O` 传播，`T_O^g` 不随 Δ 变化。∎（离线模拟：世界锚定在 Δ=5 步时 80.2% 超 10 mm，物体锚定 0%。）

**引理 L9（best-of-K 的单调性）** 对 K 个候选，真实成功 `y_i ~ Bernoulli(p_i)`，观测分 `s_i = f_i + ε, ε~N(0,σ²)`，选 `argmax s_i`。则选中成功率对 K 单调不减、对 σ² 单调不增；σ=0 时等于 `1 − E[∏(1−p_i)]`。∎（离线模拟：K=8 时 σ=0/1/2 分别为 0.789/0.706/0.632。）

**引理 L10（计划切换的净收益）** 在安全切换点，切换 `p→p'` 的期望净收益 `ΔU = [s(p')−s(p)]·P(reach|safe) − C_switch`；仅当 `ΔU>0` 时切换不劣于保持。若 `s` 校准良好且 `C_switch` 由数据估计，则"只在 ΔU>0 时切换"弱占优于"每来新计划就切"。∎

**引理 L11（异步的延迟隔离）** 若规划器运行在独立进程/线程并受资源配额约束，边端只对 `PlanBus.latest` 做原子读、从不等待规划完成，则边端 p99 延迟与规划延迟 `τ_c` 无关；唯一残余耦合是物理资源争用，可由配额/独立卡消除。∎

**引理 L12（任务条件化优于抓取条件化）** 若下游成功对抓取姿态敏感（`∂P(down|p)/∂R ≠ 0`）且与"抬升稳定性"不完全相关（相关系数 <1），则 `argmax_p P(down|p) ≠ argmax_p P(lift|p)` 一般成立；存在一个两抓取反例：`p1` 抬升更稳但锁死插入轴，`p2` 抬升略差但插入轴自由，`P(down|p2) > P(down|p1)`。∎

**引理 L13（机队记忆的迁移界）** 设成功概率对物体描述子满足 Lipschitz 常数 `L`，检索到的计划与原物体相似度 `sim`，则复用期望成功 `≥ ŝ − L·(1−sim)`；当 `sim < 1 − ŝ/L` 时下界为负，说明**低相似度不得复用**。∎（对应 E631 的相似度阈值。）

**引理 L14（失效可辨识性）** 若残差 `r_t`、跟踪置信度 `c_t`、视觉变化 `ΔI_t` 均可观测，且跟踪误差分布有界尾部，则存在阈值 `(ρ, c_min, ι)` 使漏检概率与误报概率可按 ROC 权衡；取保守阈值可令误报率 ≤5% 同时漏检率 ≤20%（预注册目标）。∎

## 12. 本轮最值得押注的创新点（一句话）

**押注 IP-09 + IP-10 的"任务条件化抓取规划 + 物体锚定边端伺服"组合：它把上一轮"事后确认抓握"推进为"事前规划抓取"，并用物体坐标系把云端慢规划与边端快执行解耦——这正好同时命中 teaser 榜的插入/旋转洼地（21.35 vs 30.3）与官方对 per-step 延迟可信度的硬要求，而单自由度、无触觉的接口决定了"抓法与下游兼容性"是绕不开也几乎无人显式建模的一步。**
