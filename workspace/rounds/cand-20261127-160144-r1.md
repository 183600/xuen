## 1. 直觉解释（先给画面，再给形式）

**灵感 1：课程学习（Curriculum Learning）——把「难度」当成可调度的资源，而不是任务的固有标签。**
直觉：32 个任务难度天差地别，但比赛要求一个模型全会。均匀采样会把梯度浪费在「已经会」和「怎么都不会」的两端，真正有学习收益的是中间地带。更关键的是，这场比赛的「难度」不是任务的固定属性，而是**标称成功与扰动成功之间的落差**：标称 95%、换背景后 40% 的任务，课程价值远高于标称 60%、换背景后 55% 的任务。所以课程的对象不该是「任务排序」，而该是「泛化缺口/失败模式」。反直觉点：**多任务比赛里根本不能做「先易后难」的任务排序（会灾难性遗忘且必须全覆盖），课程只能实现为「随能力变化的采样权重 + 探索下限」，而不是一张时间表。**

**灵感 2：成功率（Success Rate）——它既是成绩单，也是唯一可反复测量的稠密反馈控制信号。**
直觉：排行榜看成功率，但成功率是二值、稀疏，且每任务只测很少几次。若直接拿观测成功率去排「弱任务」，小样本噪声会主导排序（n=10、p=0.5 时 95% 区间约 ±0.31），课程会追着噪声跑，甚至形成「越不采样→越显得差→越不采样」的饥饿反馈。正确姿势是把它当**带不确定性的控制变量**：用分层贝叶斯收缩去噪，用序贯试验分配决定下一次真机预算花在哪，用稠密的步骤分势能代替二值成功率去驱动训练课程。反直觉点：**成功率适合「验收」，不适合「当训练权重」；训练该追步骤分势能，验收才看成功率。**

**两词碰撞出的本轮主线命题：**
> **把成功率从「成绩单」降格为「带噪声的控制信号」，把课程学习的对象从「任务」换成「标称-扰动成功率差（泛化缺口）」，并用分层贝叶斯 + 探索下限，防止小样本成功率把难任务饿死。**

## 2. 严谨定义（把直觉钉成可计算对象）

### 2.1 成功率：带噪声的潜变量，而非可观测量
对任务 i，真实成功率 S_i∈[0,1]；练习/评测得到 k_i 次成功、n_i 次试验，k_i ~ Binomial(n_i, S_i)。用分层 Beta 先验 S_i ~ Beta(μκ,(1−μ)κ)，后验均值（收缩估计）为
  Ŝ_i = (μκ + k_i) / (κ + n_i)。
小 n_i 的任务被拉向全局均值 μ，避免一次运气决定「弱任务」判定。定义「确实弱」判据：P(S_i < S_target | data) > 0.95 才进入强化名单。离线与在线成功率用带域偏置的层级模型融合：logit S_i^on = logit S_i^off + b_i，b_i ~ N(β, τ²)，b 由 I8 注册表的成对观测回填——让「离线成功」校准到「真机成功」，而不是直接冒充。

### 2.2 课程学习：时变采样分布 + 覆盖保证
把课程定义为训练支撑集 X=(任务, 泛化轴条件, 扰动剂量, 轨迹段) 上的时变采样分布 {w_t}。难度 d(x)，能力 c_t。学习带课程：
  w_t(x) ∝ p_0(x) · exp(−β_t d(x)) · b(c_t(x)),  β_t→0，
并强制探索下限 w_t(x) ≥ ε·p_0(x)。**结论（非严格证明）**：只要 ε>0，每个任务/条件的期望采样次数随训练步线性增长，故不会饥饿；β_t→0 保证最终覆盖回到 p_0，避免遗忘。关键设计：难度坐标用**泛化缺口** d_i = max(0, S_i^nom − S_i^perturbed)，稠密代理用**步骤分势能** Φ_i=E[step score]；二值成功率只做验收与预算分配（见 PR6）。

### 2.3 成功率门控的推理：把算力花在低成功节点
设校准的成功预测器 h(o)=P(success|o)（用 Brier/ECE 校准）。模块 m∈{恢复 I5, 前瞻 I7, 长 chunk I4} 成本 c_m、期望收益 Δ_m(h)。在延迟预算 B 下解 0/1 背包：max Σ Δ_m(h) s.t. Σ c_m ≤ B。高 h 走长 chunk 并跳过恢复/前瞻；低 h 触发恢复/前瞻并缩短 chunk。目标从「最大化二值成功率」改为「最大化期望步骤分 E[score]=Σ_j P(reach checkpoint j)」，避免为二值成功牺牲步骤分。

## 1. 关键伪代码

### 1.1 SRAC 采样器（缺口难度 + 学习带 + 探索下限）

```python
import math

class BetaPosterior:                     # 分层收缩：小 n 拉向全局均值
    def __init__(self, mu=0.5, kappa=2.0):
        self.a, self.b = mu * kappa, (1 - mu) * kappa
    def update(self, k, n):
        self.a += k; self.b += n - k
    def mean(self):
        return self.a / (self.a + self.b)

class SRAC:
    def __init__(self, tasks, p0, eps=0.15, beta0=4.0, anneal=50_000):
        self.tasks, self.p0, self.eps = tasks, p0, eps
        self.beta0, self.anneal = beta0, anneal
        self.post = {t: BetaPosterior() for t in tasks}   # 成功率后验
        self.phi = {t: 0.5 for t in tasks}                # 步骤分势能 Φ∈[0,1]
        self.nom = {t: 0.5 for t in tasks}                # 标称成功率

    def update(self, t, k, n, phi, nom):
        self.post[t].update(k, n); self.phi[t] = phi; self.nom[t] = nom

    def gap(self, t):                        # 难度 = 泛化缺口，不是任务身份
        return max(0.0, self.nom[t] - self.post[t].mean())

    def weights(self, step):
        beta = self.beta0 * max(0.0, 1 - step / self.anneal)   # 退火到 0
        raw = {}
        for t in self.tasks:
            band = 4.0 * self.phi[t] * (1 - self.phi[t])       # Φ=0.5 最大
            raw[t] = math.exp(-beta * self.gap(t)) * band
        z = sum(raw.values()) or 1.0
        # 探索下限：ε 比例强制均匀，防「越不采样→越显差→越不采样」
        return {t: (1 - self.eps) * raw[t] / z + self.eps * self.p0[t]
                for t in self.tasks}
```

def prob_weak(post, thr=0.5):

def allocate_next(post, tasks, rng):

def paired_ab(succ_a, succ_b):

class SuccessGatedPolicy:
    def get_action(self, obs):
        h = self.success_head(obs)                     # 已校准 P(success|obs)
        budget = self.latency_budget_ms()
        # 高成功：长 chunk、跳过恢复/前瞻；低成功：短 chunk、按预算启用模块
        horizon = 16 if h >= self.h_high else (8 if h >= self.h_low else 4)
        chunk = self.vla.propose_chunk(obs, horizon=horizon)

        candidates = []
        if h < self.h_low:
            candidates.append(("recover", self.i5.retry_cost, self.i5.retry_gain(h)))
            candidates.append(("lookahead", self.i7.cost, self.i7.gain(h)))
        for name, cost, gain in knapsack(candidates, budget):   # 只买划算的

## 2. 实验设计（课程消融 + 统计协议）

### 2.1 课程变体（L0 免费，主实验）

| 代号 | 课程 | 预期 |
|---|---|---|
| C0 | 均匀（样本数比例，官方默认） | 基线，弱任务洼地 |
| C1 | 逆成功率（朴素） | 易饥饿：难任务被持续降采样 |
| C2 | 学习带（仅 Φ） | 抗两端浪费，但忽略泛化轴 |
| C3 | 缺口难度（本点） | 直接攻击泛化缺口 |
| C4 | C3 + CVaR 尾部目标 | 进一步抬最弱任务 |
| C5 | C4 + 贝叶斯收缩 + ε 下限 | 完整 SRAC |

**指标**：最弱任务成功率（min）、平均成功率、平均步骤分、样本效率（达到目标所需步数）、饥饿率（采样占比 <ε/2 的任务数）、遗忘量（早期任务成功率跌幅）。

**统计**：每配置每任务 ≥N 次；报告 Beta 后验均值与 95% 可信区间，不报裸点估计；配置间用配对 bootstrap + 序贯停止；「最弱任务排序」用 I11 的误排率衡量。

### 2.2 分级消融

| 级别 | 内容 | 判据 |
|---|---|---|
| L0 | C0–C5 课程变体；ε∈{0,0.05,0.15,0.3}；β0 退火速率；带函数 {Φ(1−Φ), 硬带} | 缺口课程 Δ最弱任务>0 且平均不降；ε=0 出现饥饿即证伪 C1 |
| L1 | 2^(k−p) 析因：{缺口 vs 任务} × {带 vs 均匀} × {ε 有/无} × {CVaR λ} | 主效应显著的 ≤3 组合进 L2 |
| L2 | top-2 课程，≥3 任务（含 2 个弱任务）× 各 ≥10 次 | 真机最弱任务提升 ≥ 离线预测 50% |
| 门控 | 常开/常关/门控三档；可靠性图 + Brier/ECE | 门控期望步骤分 ≥ 常开，且 p99 < 40ms |

### 2.3 成功率门控校准协议

1. 留出集按任务分层切分，成功头输出经温度缩放校准；
2. 报可靠性图、Brier、ECE；ECE>0.1 视为不可用于门控；
3. 用误触发代价表（漏触发损失 / 误触发延迟）选 h_low/h_high；
4. 滑窗监控 ECE，漂移超阈即退回固定策略；
5. 消融：`h` 用真实标签 oracle 作为上界，量化校准损失。
