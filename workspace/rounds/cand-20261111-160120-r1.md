# 第 55 轮（承接第 54 轮 v16 GroundEdge-GenSim+++；灵感循环第 6 轮；本轮灵感：「实例分割」×「推理延迟」）

> 第 54 轮把技能从「能力」推进到「动作空间占用 + 云边粗细分层 + 动作-鲁棒性联合证书」，得到 v16+++。本轮把镜头从「动作空间」移到 **感知如何为动作供料**：技能真正依赖的不是整幅图像，而是**若干具体实例**；而实例分割的精度不是免费的，它由**推理延迟预算**换来的。核心矛盾：H22：现有证书把感知当作「已给定、均匀可靠」，但同一场景里不同实例的分割质量与延迟代价差异巨大，安全关键实例往往最贵，全局统一延迟上限会导致**关键实例被系统性欠分割**；H23：按整图（scene-level）组合出的技能链，在实例级感知上并不共享同一批对象——组合证书没有声明「依赖哪些实例、每个实例分到多少延迟、何时该降级」，于是组合在真实边端因实例身份漂移或掩码质量崩塌而失效。

## 0. 直觉与动机

**灵感 1（实例账本 → 把「感知就绪」拆成逐实例的可用性账本）**
直觉：说「感知可用」是个平均主义幻觉。技能 S 真正需要的是实例集合 `I_S = {i_1,…,i_m}`（例如「那杯水」「左边那把手」），而不是全图 mIoU。于是把感知状态记成一本**实例账本** `ℒ = {(id_i, mask_i, conf_i, q_i, L_i, τ_i)}`：每个实例有自己的掩码、置信、质量、已花延迟与时效。技能的前置条件从 `ρ_S ≥ ρ_min` 升级为「`I_S` 中每个实例的账本项满足 `q_i ≥ q_min` 且 `τ_i ≤ τ_max`」。这把「感知」从布尔量变成**可查账、可审计、可局部降级**的资源。

**灵感 2（延迟-质量前沿 → 实例分割是 anytime 的，延迟是可兑换的精度）**
直觉：实例分割不是「算完/没算完」的二值过程。给定更多延迟，一个 anytime 分割器（多尺度、级联 refine、更多 proposals）会给出更高的掩码 IoU。因此每个实例存在一条**延迟-质量前沿** `Q_i(L)`：投入 L 毫秒，期望掩码质量是多少。`Q_i` 单调不减、通常凹（边际收益递减）。这条曲线是本轮的第一性对象——它把「推理延迟」从工程常数变成**可分配、可竞价、可写进证书**的预算。

**灵感 3（实例预算分配 → 安全关键实例优先的注水/背包）**
直觉：总延迟预算 `L_total` 是硬的，实例的边际收益不同。安全关键实例（可能被机械臂碰撞、被操作对象）应优先注水，背景装饰物应允许降级。把预算分配写成带权最大化：`max min_i (w_i·Q_i(L_i))` 或 `max Σ κ_i·Q_i(L_i) s.t. Σ L_i ≤ L_total`，其中 `κ_i` 为实例关键度。这是一个**注水/背包混合问题**，其解天然给出「哪些实例吃满、哪些实例被降级到最低可接受质量」的分级策略，而不是一刀切的全局超时。

**灵感 4（实例条件化组合 → 组合前先对齐「依赖同一批实例」）**
直觉：第 54 轮的 `compat(S_i,S_j)` 只看动作空间，漏掉了「两个技能是否在看同一批实例」。若 S1 依赖实例 A 的精细掩码、S2 依赖实例 B，则它们的组合在感知上并不耦合；但若 S1 的操作会遮挡 S2 所需的实例，则组合会触发**实例级感知冲突**（occlusion-induced perception conflict）。因此在组合图上再加一条边条件：`I_{S_i} ∩ I_{S_j}` 的**可见性保持** `vis_{S_j→S_i} ≥ θ_vis`，形成「动作兼容 ∧ 实例兼容」的双重可判定性。

**灵感 5（云边实例身份一致性 → 粗 proposals 与细 masks 的跨分辨率对账）**
直觉：第 54 轮的云边协同只对齐了动作，没有对齐**实例身份**。云端在低分辨率/粗分割上给出实例 proposal 与全局预算，边端做高分辨率 refine；两者之间必须以 `id` 对账：`γ_ce^I: id_c ↦ id_e`。若在延迟压力下边端发生**实例身份切换**（两个相邻杯子被合并/交换），即便每个掩码 IoU 都不低，下游技能仍会作用到错误对象。实例身份切换率因此成为与动作对齐误差 `δ_a` 并列的一类新风险，需要单列预算 `δ_id`。

## 1. 形式化定义（增量：定义 121–127）

**定义 121（实例账本）**
在时刻 t，感知账本 `ℒ_t = {(i, m_i, c_i, q_i, L_i, τ_i)}`，其中 `i` 为实例身份，`m_i ⊆ Ω` 为掩码，`c_i∈[0,1]` 为置信，`q_i∈[0,1]` 为质量（`q_i = IoU(m_i, m_i^*)` 的期望），`L_i` 为已投入延迟，`τ_i` 为账本项自采集以来的时龄。**实例可用** `avail(i) = 1[q_i ≥ q_min ∧ τ_i ≤ τ_max]`。

**定义 122（延迟-质量前沿与 anytime 分割）**
实例 i 的延迟-质量前沿 `Q_i: ℝ_{≥0} → [0,1]`，满足 `Q_i(0)=q_i^0`、单调不减、凹、`lim_{L→∞} Q_i(L) ≤ 1`。anytime 分割器在预算 L 下输出质量不低于 `Q_i(L) - ε_i` 的掩码，其中 `ε_i` 为校准误差。前沿可通过多档延迟 `{L^(1)<…<L^(K)}` 实测拟合。

**定义 123（实例关键度与实例条件化鲁棒性）**
技能 S 的依赖实例集 `I_S ⊆ ℒ`。实例关键度 `κ_i ∈ [0,1]` 表示该实例感知失败对任务成功的边际影响。技能 S 的**实例条件化鲁棒性谱** `ρ_S(d | ℒ_S)` 满足：`ρ_S(d | ℒ_S) = ρ_S^0(d) · Π_{i∈I_S^crit} g_d(q_i)`，其中 `g_d` 为质量-鲁棒性传递函数（单调不减，`g_d(1)=1`）。这把第 53 轮的 ρ 显式挂到实例质量上。

**定义 124（实例延迟预算分配）**
给定总预算 `L_total` 与实例集 `I_task`，分配 `{L_i}` 求解
```
max_{L_i ≥ 0}  Σ_{i∈I_task} κ_i · Q_i(L_i)
s.t.  Σ_i L_i ≤ L_total,  Q_i(L_i) ≥ q_min  ∀ i ∈ I_crit
```
其拉格朗日解为注水：`κ_i·Q_i'(L_i) = λ`（内点），关键实例受 `q_min` 下界约束，非关键实例可被压到 `L_i=0`。

**定义 125（实例感知的动作剖面与组合）**
技能动作剖面从 `α_S(a)` 细化为 `α_S(a | ℒ_S)`：仅在 `I_S` 全部 `avail` 时取原值，否则按未可用实例的影响衰减。两技能实例兼容性
```
icompat(S_i,S_j) = 1 - |I_{S_i} \ I_{S_j}^{vis}| / |I_{S_i} ∪ I_{S_j}|
```
其中 `I_{S_j}^{vis}` 为在 S_i 执行后仍可见的 S_j 依赖实例。组合可行需同时满足第 54 轮的 `compat ≥ θ_a` 与 `icompat ≥ θ_i`。

**定义 126（实例-延迟联合证书）**
`J_I = (I_core, I_buffer, ρ_I, {Q_i}, {L_i}, δ_id, evidence)`：
- `I_core` 为组合保证可用的核心实例集，`I_buffer` 为可降级实例；
- `ρ_I = ρ_{S_1⊗…⊗S_k}(d | ℒ_{I_core})` 为实例条件化组合鲁棒性；
- `{Q_i}` 为各实例在分配预算下的质量下界，`{L_i}` 为预算向量；
- `δ_id` 为云边实例身份切换率上界；
- `evidence` 含逐实例前沿校准点、预算分配解、身份对账日志。
若 `dom(ρ_I)=in`、`Q_i ≥ q_min (i∈I_core)`、`δ_id ≤ Θ_id`，则组合可部署。

**定义 127（云边实例身份对账）**
`γ_ce^I : id_c → id_e` 为实例身份映射，其误差
```
δ_id = P(id_e ≠ γ_ce^I(id_c)) + λ_m·E[1 - IoU(m_e, up(m_c))]
```
要求 `δ_id ≤ Θ_id`，且身份对账须在 `τ_loop` 内完成。动作对齐误差 `δ_a` 与身份误差 `δ_id` 共同构成云边联合误差 `δ_ce = max(δ_a/Θ_a, δ_id/Θ_id)`。

## 2. 本轮的方法论立场

第 54 轮回答「动作能不能接上」；本轮回答「**感知能不能按时供上正确的实例**」。两者是乘性的：动作对齐再好，实例身份错了就是负迁移；实例分割再准，延迟超预算导致账本过期同样不可用。因此本轮把「感知」正式纳入证书体系，且坚持三条纪律：(i) 不追求全图平均精度，只追求**任务依赖实例集**的可用性；(ii) 延迟按实例分配而非全局截断；(iii) 云边对账同时管动作与身份。

## 3. 与前沿工作的关系（定位，非引用堆砌）

实例分割的 anytime 化（级联/多尺度 refine）与「精度-延迟」帕累托分析在感知社区已有雏形，但通常以**整图 mAP/延迟**为指标；技能组合与云边协同文献通常假设感知输出是「黑箱且即时」。本轮的差异点是把**实例级延迟-质量前沿**做成可写进证书、可参与组合判定、可与云边身份对账耦合的一等公民，并与第 53/54 轮的 ρ、α_S、δ_a 形成乘性证书链。

## 4. 本轮最大风险

**一句话**：实例级延迟-质量前沿与预算分配让感知第一次「按需供料」，但其 soundness 依赖 `Q_i(L)` 的可校准性、实例关键度 `κ_i` 在 episode 内的稳定性、以及延迟压力下云边身份对账不崩；一旦前沿在分布外场景被高估、或关键实例恰好是最贵且最易被降级的那一类，预算分配会把精度从安全关键实例上「优化掉」，形成**用平均收益掩盖关键失效**的系统性盲区，故必须以分布外前沿复核 + 关键实例不可降级硬约束 + 身份切换绊线三重护栏，宁可牺牲非关键实例精度，也不让关键实例进入欠分割区。

### IP-121 ILP（逐实例延迟-质量前沿）

```python
def profile_latency_quality(skill, instance_ids, budgets, calib_set):
    curves = {}
    for i in instance_ids:
        pts = []
        for L in budgets:                       # e.g. [0, 8, 16, 32, 64] ms
            ious = []
            for scene in calib_set:
                m = anytime_segment(scene, target=i, budget_ms=L)
                ious.append(iou(m, scene.gt_mask[i]))
            pts.append((L, mean(ious), std(ious)))
        curves[i] = fit_concave_monotone(pts)    # 保单调、保凹、记录 ε_i
    return curves

def budget_feasible(curve_i, L, q_min):
    return curve_i.eval(L) + curve_i.eps >= q_min   # 下界用保守估计
```

### IP-122 IBA（关键实例优先预算分配）

```python
def allocate_budget(curves, kappa, L_total, q_min, I_crit):
    # 1) 关键实例先满足 q_min 的硬下界（不可降级）
    L = {i: 0.0 for i in curves}
    for i in I_crit:
        L[i] = curves[i].min_budget_for(q_min + curves[i].eps)
        if L[i] is None:
            return ('infeasible', i)          # 关键实例不可达标 → 否决
    rem = L_total - sum(L.values())
    if rem < 0:
        return ('infeasible', 'crit_exceeds_budget')
    # 2) 其余实例按 κ_i·Q_i'(L_i)=λ 注水（整数档位用贪心取最大边际增益）
    pool = [i for i in curves if i not in I_crit]
    while rem > 0 and pool:
        i = argmax(pool, key=lambda j: kappa[j] * marginal_gain(curves[j], L[j]))
        step = next_budget_step(L[i])
        if step is None or step > rem:
            pool.remove(i); continue
        L[i] += step; rem -= step
    # 3) 输出每实例质量下界与降级清单
    Q = {i: curves[i].eval(L[i]) for i in curves}
    degraded = [i for i in curves if Q[i] < q_min]
    return ('ok', L, Q, degraded)
```

### IP-123 ICA（实例条件化技能组合）

```python
def build_instance_aware_graph(skills, theta_a, theta_i, theta_vis):
    G = nx.DiGraph()
    for s1 in skills:
        for s2 in skills:
            if s1.id == s2.id: continue
            if jaccard(s1.alpha, s2.alpha) < theta_a:  continue   # v54 动作兼容
            vis = visibility_after(s1, s2.I)                       # s1 执行后 s2 实例可见率
            ic  = 1 - len(s2.I - vis.set) / max(1, len(s1.I | s2.I))
            if ic < theta_i or min(vis.scores.values(), default=1.0) < theta_vis:
                continue
            occl = occlusion_risk(s1, s2.I)                        # 遮挡引入的实例冲突
            G.add_edge(s1.id, s2.id, icompat=ic, occl=occl,
                       cost=transition_cost(s1,s2) + w_o*occl)
    return G
```

### IP-124 ILJC（实例-延迟联合证书）

```python
def instance_joint_certificate(skill_seq, curves, kappa, L_total,
                               q_min, gamma_ce_I, budget_id):
    I_core = critical_instances(skill_seq)          # ∪ I_S，κ_i ≥ κ_min
    I_buf  = optional_instances(skill_seq)
    r = allocate_budget({i:curves[i] for i in I_core|I_buf},
                        kappa, L_total, q_min, I_core)
    if r[0] != 'ok':
        return ('reject', r)
    _, L, Q, degraded = r
    rho_I = compose_instance_robustness(skill_seq, Q)     # 定义 123
    delta_id = identity_switch_rate(gamma_ce_I)
    if delta_id > budget_id:
        return ('reject', 'identity_switch', delta_id)
    if any(Q[i] < q_min for i in I_core):
        return ('reject', 'critical_undersegmented', I_core)
    return ('ok', JointInstanceCert(I_core, I_buf, rho_I, Q, L,
                                    delta_id, evidence=collect_logs()))
```

### IP-125 ICE（云边实例身份对账）

```python
def cloud_edge_instance_reconcile(P_c_masks, edge_fine, gamma_ce_I, tau_loop):
    t0 = now()
    id_map, err = {}, []
    for id_c, m_c in P_c_masks.items():                 # 云端粗 proposal
        id_e, m_e = edge_fine.nearest(m_c)               # 边端细分割
        iou_up = iou(m_e, upsample(m_c))
        id_map[id_c] = id_e
        err.append((1 - iou_up) + (0.0 if id_e == id_c else 1.0))
    dt = now() - t0
    if dt > tau_loop:
        return ('reject', 'loop_timeout', dt)
    delta_id = mean(err)
    return ('ok', gamma_ce_I.merge(id_map), delta_id)
```

### IP-126 AQG（账本时龄/质量跌落守卫）

```python
def anytime_quality_guard(ledger, t_now, q_min, tau_max, L_total):
    stale = [i for i,e in ledger.items() if t_now - e.t >= tau_max]
    drop  = [i for i,e in ledger.items() if e.q < q_min]
    if not stale and not drop:
        return ('ok', ledger)
    # 先重建关键实例，再按注水恢复非关键实例
    plans = [('refresh_critical', i) for i in stale if ledger[i].kappa >= K_CRIT]
    if sum(ledger[i].L for i in plans) > L_total:
        return ('degrade', 'critical_stale_exceeds_budget')   # 触发重规划/回滚
    ledger = refresh(ledger, plans, order='tau_desc')
    rest = [i for i in stale if i not in plans]
    ledger = opportunistic_refill(ledger, rest, L_total - used(plans))
    return ('ok', ledger)
```

```python
def priority_robustness_gate(J_I, tripwires):
    # 1) 关键实例永不被降级
    if any(J_I.Q[i] < J_I.q_min for i in J_I.I_core):
        return ('veto', 'critical_undersegmented')
    # 2) 负迁移绊线：历史同实例切换/遮挡曾致失败
    for i in J_I.I_core:
        if tripwires.hit(i, severity='negative_transfer'):
            return ('veto', 'tripwire', i)
    # 3) 云边联合误差双预算
    if J_I.delta_id / Theta_id > 1 or J_I.delta_a / Theta_a > 1:
        return ('veto', 'ce_error_budget')
    return ('ok', J_I)
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| ILP | O(|I|·K·|D_calib|·T_seg) | O(|I|·K) | 前沿保单调/凹，`ε_i` 保守下界 |
| IBA | O(|I| log|I| + K·|I|) | O(|I|) | 关键下界硬约束，注水最优（离散档位贪心近似） |
| ICA | O(|S|²·|I|) | O(|S|²+|E|) | 动作 ∧ 实例双重 sound，可见性显式 |
| ILJC | O(|S|·|I| + |I|log|I|) | O(|I|+|E|) | 证书四维闭合，关键不可降级 |
| ICE | O(|I|·T_match) | O(|I|) | 身份对账有界，超时否决 |
| AQG | O(|I| log|I|) | O(|I|) | 时龄优先刷新，预算不可超支 |

**正确性定理（Instance-Latency-Aware Composition Soundness）**
假设第 53/54 轮 (A22)–(A28) 成立；新增 **(A29)** 每个关键实例的 `Q_i(L)` 由校准集拟合且分布外误差 `≤ ε_i`；**(A30)** 实例关键度 `κ_i` 在单 episode 内稳定（变化 `≤ Δκ`）；**(A31)** 云边身份切换率上界 `δ_id ≤ Θ_id` 且对账延迟 `≤ τ_loop`。则组合部署成功概率满足
```
P_success ≥ 1 - Σ_d (1-ρ_min(d)) - β_E - P(δ_a>Θ_a)
            - P(∃ i∈I_core: Q_i < q_min) - P(δ_id>Θ_id) - P(κ 漂移>Δκ)
```
其中负迁移项由 IPR 绊线显式清零（hit 即否决，不计入成功）。关键点：**实例质量是 ρ 的乘性前置**，**延迟是实例级的可分配资源**，**身份对账与动作对账同等重要**。

**推论（预算单调性）**：固定 `I_core`，增大 `L_total` 不会降低任何关键实例的质量下界，非关键实例质量单调不减；但若 `L_total` 低于关键下界之和，应返回 `infeasible` 而非静默降级——这是与「全局超时截断」最本质的区别。

## 4. 实验设计 E162–E166

| 实验 | 指标 | 目标 |
|---|---|---|
| E162 前沿校准精度 | `|Q_i(L)-Q_i^real(L)|`、分布外误差 | MAE ≤ 0.03 IoU，OOD P95 ≤ 0.06 |
| E163 预算分配收益 | 关键实例 mIoU vs 均分/全局截断 | 关键 mIoU +10%，总延迟不增 |
| E164 实例条件组合 | 虚假兼容率 / 可行路径发现率 | 误报 ≤ 4%，发现率 ≥ 88% |
| E165 云边身份一致性 | `δ_id`、身份切换率 | `δ_id ≤ 0.02`，切换率 ≤ 1% |
| E166 端到端部署 | 成功率、P99 延迟、降级率 | 成功率 +15% vs 固定超时，P99 ≤ 预算 |

**消融**：去掉 IBA（均分）、去掉 ICA（仅动作兼容）、去掉 ICE（仅动作对账）、去掉 IPR（允许关键降级）四组，分别量化关键实例欠分割率、负迁移率、身份切换致败率。**负结果判据**：若 E163 中关键实例收益 < 3% 或 E165 `δ_id` 无法压到 0.05 以下，则本轮「实例级延迟分配」假设不成立，应退回整图 anytime 方案。

## 6. 本轮最大风险

**一句话**：实例级延迟-质量前沿与预算分配让感知第一次「按需供料」，但其 soundness 依赖 `Q_i(L)` 的可校准性、实例关键度 `κ_i` 在 episode 内的稳定性、以及延迟压力下云边身份对账不崩；一旦前沿在分布外场景被高估、或关键实例恰好是最贵且最易被降级的那一类，预算分配会把精度从安全关键实例上「优化掉」，形成**用平均收益掩盖关键失效**的系统性盲区，故必须以分布外前沿复核 + 关键实例不可降级硬约束 + 身份切换绊线三重护栏，宁可牺牲非关键实例精度，也不让关键实例进入欠分割区。
