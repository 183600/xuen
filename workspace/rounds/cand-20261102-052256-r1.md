# 第 1 轮（新灵感循环；承接第 12 轮 CHUNK-SERVO）· PAIN-FED：先把「哪里痛」测出来，再用联邦标定与人为干扰预警去止痛

> 检索/复核日期：**2026-11-02（UTC）**。赛事身份已再次核实：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新的灵感循环第 1 轮，三个随机词是「**痛点分析**」「**联邦学习**」「**面部表情识别**」。本轮不推倒第 12 轮 CHUNK-SERVO，而是先修它的四个事实错误，再把「最后 3 厘米」从控制问题扩展成「测量—分配—恢复」问题：**PAIN-ATLAS 负责测哪里痛，FED-CAL 负责在多机器人上不重复犯错，HUMAN-WATCH 负责在人为干扰前进入安全态。**

## 0. 先给结论：榜首不到 30%，缺的不是又一个模型，而是一个「测量层」

如果只看「32 任务、单模型、远程 API、榜首不到 30%」，最自然的反应是再训一个更大的 VLA，或者再堆一个世界模型。第 12 轮已经把「执行层」推到了 CHUNK-SERVO：30 步规划 + 5 步视觉伺服。本轮我想先退一步问一个更上游的问题：

> **我们到底知不知道失败发生在哪里？**

我的答案是：**不知道，而且公开信号不足以下这个判断。**

- 排行榜只有 8 个模型、32 个任务的预览行；`runs.html` 的 256 条记录里，任务成功率出现 23.8%、28.2%、19.1%、16.7%、37.0%、30.5%、17.1% 这类数字，**不是 10 次试次能产生的 10% 整数倍**。它不能当失败分布。
- 每个任务正式评测只有 10 次；`p≈0.25` 时全局 320 次的标准误约 **2.42pp**，单任务分辨率是 **10pp**。这意味着：**任何「某任务涨了 3pp」的说法，在 10 次试次下都不可辨识。**
- 33k 演示全是成功，不含失败标签；但它们能告诉我们任务在**哪里「承诺」**：夹爪开合次数、低速段占比、离终点的距离、轨迹曲率。这些是「触点」的可观测代理，不是失败率。

所以本轮的核心判断是：

> **在不知道痛点分布的情况下，继续加模型、加算力、加 32 个任务的工程，边际收益都会被「试次噪声 + 任务错配」吃掉。先把痛点图谱测出来，再决定把工程投到哪 6–10 个任务，是本轮最高性价比的创新。**

一句话押注：

> **把 320 次真机试次当成一个跨机器人、隐私保护的联邦实验：用 33k 成功演示 + 单任务通道建立「任务 × 失败模式 × 泛化轴」的痛点图谱，只把工程投到 `q_t×Δ/cost` 最高的 6–10 个任务；用联邦标定只共享每台机器人的低维校准量（不共享模型权重）；用头部相机的「人进入工作区」检测而不是字面表情识别，抢在人为干扰前进入安全态。**

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 明确不做什么 |
|---|---|---|
| **痛点分析** | PAIN-ATLAS：任务 × 失败模式 × 泛化轴的矩阵；用触点代理 + 单任务 A/B 更新；按 `q_t×Δ/cost` 分配 320 trials | 不把预览榜单当失败图谱；不用任务时长/工作空间大小当难度；不在 10 次试次上宣称单任务 3pp 显著 |
| **联邦学习** | FED-CAL：每机器人 6–12 维校准量，闭式估计 + 稳健聚合；FED-EVAL：分层 bootstrap；FED-ATLAS：只传聚合失败签名 | 不做跨队联邦训练；不联邦训 VLA 权重；不做每端口不同策略网络；不共享原始图像/人类纠正数据 |
| **面部表情识别** | HUMAN-WATCH：手/臂进入、物体位移、头姿弱先验；字面 FER 只留 B 级观察 | 不在主线上做情绪分类；不假设头部相机能稳定拍到脸；不把表情当因果信号 |

## 2. 痛点分析：为什么「平均成功率」是一个坏指南针

### 2.1 320 次试次的统计分辨率

总分：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad p_t=\frac{1}{10}\sum_{j=1}^{10} y_{t,j}.
```

若 `p≈0.25`，320 次试次的全局标准误：

```math
\mathrm{SE}(S)\approx\sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

单任务 10 次试次的标准误约 `sqrt(0.25×0.75/10)=0.137`，即 **13.7pp**；实际能分辨的最小效应接近 **10pp 粒度**。因此：

- 「某任务从 20% 到 23%」在 10 次试次下无法作为结论；
- 只有把**同类失败模式的任务池化**（例如 8 个插入类任务），才能谈 3–5pp 的全局效应；
- 任何 A/B 必须**配对**（同初始条件、同背景、同机器人），并用 bootstrap 给差值置信区间，而不是比较两个平均值。

### 2.2 公开榜单不能当失败图谱的三个理由

1. **口径不匹配**：runs 页的成功率不是 10% 整数倍，与「每任务 10 次」矛盾；不能从中反推每任务失败次数。
2. **任务级相关太弱**：第 12 轮在公开 JSON 上做过跨模型任务级相关（平均 off-diagonal ≈0.098）；如果任务难度是真实的，不同模型在同一任务上的成功率应正相关。弱相关更像「每个模型独立生成的预览曲线」，而不是同一套真机试次。
3. **没有失败模式标签**：即使数字是真的，也只有「成功/失败」，没有「失败在抓取、插入、还是人为干扰」。痛点分析需要的恰恰是后者。

### 2.3 用成功演示挖「触点」：一个可复现的 pilot

33k 演示全是成功，但成功轨迹里有「承诺点」。我用 HuggingFace datasets-server 的 `rows` API 抽取每个任务 **episode 0** 的前若干帧（2026-11-02），计算：

- `flips`：夹爪开/合阈值（<1.0）穿越次数；
- `slow`：EE 速度 < 2 cm/s 的帧占比；
- `d5`：离最终 EE 位置 ≤5 cm 的帧占比；
- `curv`：EE 路径长度 / 首尾直线距离；
- `close_frac`：首次闭合前的帧占比。

Pilot 结果（**仅 episode 0，不是全数据集结论**）：

|---|---:|---:|---:|---:|---:|---:|---|
| HangCup | 214 | 7.1s | 2 | 16.9% | 8.4% | 8.3 | 短、两次抓取、接近段占比小 |
| StackBowls | 480 | 16.0s | 2 | **49.9%** | 13.1% | 41.4 | 长时间低速对位 |

### 2.4 一个反直觉结果：任务时长/工作空间与「接触痛点」方向相反

用 32 个 `stats.json` 构造一个粗糙的「运动承诺」分数（时长 + pivot 高度/yaw/base + 夹爪行程 + EE 工作空间 + 下身体跨度，z-score 求和），排序头部是：

```text
OrganizeTools, StorePaddle, FoldTowel, PackDoll, OrganizeBookshelf, ToolboxStorage, PackBag, StoreCups, ZipUp, PlugInEthernet
```

而语义上最像「最后 3 厘米」的插入/挂/叠任务，很多排在底部：

```text
PlugCharger, StackBowls, RemovePinnedNote, PourOutMedicine, DisconnectEthernet
```

把第 12 轮的 19 个 A 档（接触优先）与 13 个 B 档（VLA 优先）对比，A 档的平均运动承诺分数 **-0.76**，B 档 **+1.12**。也就是说：**「任务长、动得多、工作空间大」与「终局需要毫米级接触」不是同一个维度，甚至方向相反。** 这直接否定了「按时长/难度表分配工程」的直觉，也说明为什么需要一个显式的痛点矩阵，而不是一个「难度分」。

### 2.5 PAIN-ATLAS 的定义

把痛点写成一个三维矩阵，而不是一个标量：

```text
P[t, m, g] = 任务 t 在失败模式 m、泛化轴 g 上的痛感（0–1）
m ∈ {F1 识别/语义, F2 接近/抓取, F3 搬运/碰撞, F4 接触/插入(<3cm), F5 人为干扰, F6 超时/长程}
g ∈ {position, distractor, background, unseen, human}
```

每个格子的来源分三层：

1. **先验**：任务语义（是否有插入/挂/叠/拉链/拧/锁）+ 演示触点代理（flips/slow/d5/curv）；
2. **单任务通道**：每任务 5 次 A/B（servo off/on 或 pivot 零/先验），记录成功、步骤分、耗时、p99、失败阶段；
3. **正式评测**：只在通过门后跑 32×10；正式结果回填矩阵，但**不用单任务 5 次的结果宣称全局显著**。

派生量：

```text
q_t   = P[t, F4, *] / Σ_m P[t, m, *]       # 失败落在最后 3cm 的比例（先验/实测）
Δ_t   = 条件增益（A/B 配对差值）
cost_t= 工程/评测成本
priority_t = q_t * Δ_t / cost_t
```

**分配规则**：先把工程投到 `priority_t` 最高的 6–10 个任务；其余任务只保留 VLA 基线 + P0 pivot 修复，不铺伺服/目标库。每测 3–5 个任务更新一次矩阵；如果某任务的 `q_t` 低但 `Δ_t` 高，说明增益来自非接触因素（例如背景鲁棒性），应改投 VLA 数据增强而不是伺服。

## 3. 联邦学习：在「单模型」规则下，什么能联邦、什么不能

这是本轮最容易被误用的词。先把边界说死。

### 3.1 不能做的四件事

| 做法 | 为什么不做 |
|---|---|
| 跨队联邦训练 VLA | 32 任务数据已集中公开在 HF；跨队没有额外数据优势；涉及数据协议、公平性、排行榜竞争；赛事要求同一模型，跨队聚合会产生不可审计的权重来源 |
| 联邦训练/微调 VLA 权重 | 每个 client 的权重会漂移，破坏「同一模型」；通信/算力成本高；评测是短时远程调用，来不及多轮 |
| 每端口一个策略网络/适配器 | 直接违反「单模型、不得混合多个模型」；即使结构相同，不同权重也会被质疑 |
| 共享人类纠正数据/原始图像 | 隐私、同意、规则不明确；对本赛事也没有数据量优势 |

近期工作确实证明联邦 VLA 可行：Co-VLA（arXiv 2609.19923）用 ADMM 做共识优化；FedDRMan（arXiv 2609.32239）用低秩子空间蒸馏处理 non-IID；联邦微调 testbed（arXiv 2609.22973）系统研究了参数范围；「When Human Corrections Travel」（arXiv 2610.32888）专门讨论人类纠正的联邦共享与安全。**但这些工作的前提是「数据分布在多个站点、不能集中」；UniBot 恰好相反——数据集中、评测分散。** 所以正确的迁移不是「联邦训模型」，而是「**联邦做评测与校准**」。

### 3.2 能做的三件事

#### FED-CAL：每机器人 6–12 维校准量

不共享权重，只共享「这台机器人/这个端口」的低维校准向量：

```text
θ_i = [ δT_head(6), δT_wrist(6), K_p(1), K_d(1), τ(1), gripper_offset(2) ]  # 约 12–17 维
```

- `δT_head/δT_wrist`：相机外参修正（用重投影误差闭式最小二乘估计）；
- `K_p/K_d`：伺服增益（用阶跃响应/小步试探估计）；
- `τ`：端到端延迟（用时间戳互相关估计）；
- `gripper_offset`：夹爪零位/行程偏差（用开合极限估计）。

**关键合规点**：

- VLA 权重在所有端口**完全相同**（同一 checkpoint 哈希）；
- `θ_i` 用**闭式最小二乘 / 稳健滤波 / 贝叶斯更新**估计，**不做梯度训练**；它不是策略网络，是标定参数；
- 若官方对「模型」作最宽解释，退到 C1：只用一个全局 `θ`，不做 per-port 适配；或只用测量、不写回控制。

聚合：

```text
θ_global = median_i(θ_i)            # 对异常机器人稳健
θ_i* = θ_global + clip(θ_i - θ_global, ±δ)   # 保留小幅个体差异
```

只传 `θ_i`（十几维浮点），不传图像、不传梯度、不传权重。带宽可忽略。

#### FED-EVAL：跨机器人/端口的配对实验账本

每个端口记录配对 A/B 的 `(task, gen_axis, y_off, y_on, step_off, step_on, latency)`；服务器做**分层 bootstrap**：

```text
for b in 1..B:
    resample robots with replacement
    resample tasks within robot with replacement
    resample paired trials within task with replacement
    Δ_b = mean(y_on - y_off)
CI = percentile(Δ_b, [2.5, 97.5])
```

这解决两个问题：

- 单任务 5 次 A/B 的方向性结果不会被误当成全局结论；
- 机器人/光照异质性被显式建模，而不是把 N 台机器人的数据混在一起平均。

#### FED-ATLAS：只传聚合失败签名

每个端口只上报：

```text
(task_id, gen_axis, failure_mode, phase, distance_to_contact_mm, gripper_flips, latency_ms)
```

不上传图像、不传轨迹、不传物体身份。服务器按 `(task, mode, axis)` 聚合，形成全局痛点矩阵。这是「隐私保护的失败图谱」，也是本轮真正的「联邦」价值：**联邦的是证据，不是模型。**

### 3.3 一句话总结

> **UniBot 不是一个联邦学习 benchmark，但它的评测是联邦的：N 台机器人、N 个端口、不同光照/标定/延迟。所以应该联邦「实验」和「校准」，而不是联邦「权重」。**

## 4. 面部表情识别：剪掉字面词，保留「人进入工作区」

### 4.1 字面 FER 为什么不该放在主线上

| 问题 | 具体 |
|---|---|
| 相机不对 | 头部双目朝桌面，不是人脸；人站在桌边时脸可能在画面顶部边缘或画外 |
| 分辨率不够 | 480×640，人距 1–2 m，脸可能只有 30–60 px；运动模糊、逆光 |
| 没有标签/因果链 | 任务里的人类干扰是「移动物体」，不是「表达情绪」；即使 100% 识别愤怒/高兴，也不能告诉你哪个物体会被移动、何时移动 |
| 隐私/合规 | 录脸、情绪推断涉及隐私与偏见；赛事没有要求，也没有同意流程 |
| 成本/收益 | 训练/部署一个人脸情绪模型，换不来可归因的成功率提升；还会增加「第二个模型」的合规风险 |

**结论：字面 FER 从主线剪掉，只保留 B 级观察。** 这不是说 FER 没价值，而是它在**当前 API + 当前任务**里没有因果路径。近期 Hand2Bot（arXiv 2608.13028）确实用面部表情做 human-to-robot handover 的意图预测；HRC 情绪工作（arXiv 2605.16816）也证明上下文 VLM 能改善情绪理解。但 handover 有面对人的相机和递物意图，UniBot 是桌面操作 + 物体位移，**域不匹配**。

### 4.2 重构：HUMAN-WATCH

把「表情」换成「人进入工作区的运动学证据」：

```text
输入：head_stereo_left/right（480×640）、左右腕部图、EE 位姿
特征：
  motion_energy      = 工作区 ROI 的帧差/光流能量
  hand_blob          = 肤色/运动连通域（经典 CV，不做深度学习）
  object_displacement= GEO-RESIDUAL 的物体位移残差
  head_pose_prior    = 若人脸/头可见，头朝向工作区的角度（弱先验，可选）
分数：
  human_score = w1*motion_energy + w2*hand_blob + w3*object_displacement + w4*head_pose_prior
```

状态机：

```text
WATCH ──human_score > θ_watch──▶ APPROACH
APPROACH ──持续 K 帧 / 物体位移──▶ HOLD_SAFE
HOLD_SAFE ──人离开 + 目标可见──▶ RELOCALIZE ──▶ RESUME
HOLD_SAFE ──目标不可见/被拿走──▶ REPLAN ──▶ RESUME
任意状态 ──超时/最大重试──▶ FAIL_GRACEFUL
```

延迟预算：**100–200 ms**；CPU-only；不做第二个学习策略。若使用现成的人体检测器，只作为「传感器」而不是策略，并在提交材料里写清楚（C2/C3）。

### 4.3 算术：为什么 human 轴值得做

人为干扰轴占每次评测的 **2/10 = 20%**（官方手册：5 类泛化各 2 次）。若 human 轴成功率提升 `Δp_h`：

```math
\Delta S_{\mathrm{human}} = 0.2\,\Delta p_h.
```

- `Δp_h = +10pp` → 全局 **+2.0pp**；
- `Δp_h = +20pp` → 全局 **+4.0pp**；
- 若同时把「检测延迟」从 1 个 chunk 降到 200ms，减少碰撞/物体掉落，收益可能更高，但必须用配对实验证明。

对比：修 10 个接触任务各 +10pp → `10/32×10 = +3.1pp`。**human 轴 + 接触任务池化，是本轮两条最清晰的边际收益曲线。**

## 5. PAIN-FED 总架构

```text
                    ┌─────────────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1)         │
                    └──────────────┬──────────────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
        ┌──────────────────────────────────────────────────────────┐
        │  Per-port PolicyService (CPU)                            │
        │  ├─ PAIN-ATLAS router: 选择当前任务的失败模式/阶段        │
        │  ├─ HUMAN-WATCH: 帧差/手部/物体位移 → HOLD/RELOC        │
        │  ├─ CHUNK-SERVO: 30 步 plan + 3/5/8 步伺服              │
        │  ├─ DG-KEYFRAME: 演示检索的相对目标（保留）             │
        │  ├─ FED-CAL: θ_i 校准（外参/增益/延迟/夹爪）            │
        │  └─ action adapter (WLA 54D → API 21D)                  │
        └──────────────┬───────────────────────────────────────────┘
                       │ 只传低维统计：θ_i / 失败签名 / 配对结果
                       ▼
        ┌──────────────────────────────────────────────────────────┐
        │  Shared server (CPU + 1 GPU)                             │
        │  ├─ 唯一 VLA checkpoint（同一哈希，所有端口共享）        │
        │  ├─ FED-CAL: 稳健聚合 θ_global                           │
        │  ├─ FED-EVAL: 分层 bootstrap                             │
        │  └─ FED-ATLAS: 全局痛点矩阵                              │
        └──────────────────────────────────────────────────────────┘
```

关键约束：

- **唯一学习模型**是 VLA；HUMAN-WATCH / 视觉伺服 / FED-CAL 都是确定性控制器或统计估计；
- 每个端口 `reset()` 隔离；痛点矩阵/目标库只读共享（copy-on-write）；
- 图像、轨迹、人脸**不出端口**；只上传低维统计；
- 同一 checkpoint 哈希在所有端口可审计。

## 7. 竞赛策略：320 trials 是投资组合，不是 32 个盲测

### 7.1 分诊与分配

```text
priority_t = q_t * Δ_t / cost_t
```

- 先做 **P0 PIVOT-PRIOR**（几乎零成本，可能白捡）；
- 再做 **A 档 6–10 个任务**的 CHUNK-SERVO + HUMAN-WATCH；
- 其余任务只保留官方 WLA 基线 + 必要的数据增强；
- 每 3–5 个单任务 A/B 更新一次 `q_t/Δ_t/cost_t`；
- 正式提交前，用 FED-EVAL 的分层 bootstrap 确认全局效应 CI 不跨 0。

### 7.2 单任务通道协议

| 项 | 设计 |
|---|---|
| 任务 | 先 5 个：PlugInEthernet（插入）、HangCup（挂）、ZipUp（拉链/多次抓取）、StackBowls（慢速对位）、FoldTowel（变形，防回归） |
| 次数 | 每任务 5 次 A/B（servo off/on；pivot 零/先验） |
| 指标 | 成功、步骤分、耗时、p99、失败阶段、human_score 误报 |
| 通过 | ≥3/5 任务 +10pp；FoldTowel 不回归 >5pp；p99 ≤150ms |
| 统计 | 配对差值 + bootstrap 95% CI；不宣称单任务 3pp 显著 |

### 7.3 提交节奏

1. **W0**：WLA + API adapter + P0 PIVOT-PRIOR；单任务通道跑通 1 个任务，确认 token/chunk/pivot。
2. **W1**：PAIN-ATLAS v0（32 任务触点代理 + 5 任务 pilot）；决定 6–10 个主投任务。
3. **W2–W3**：CHUNK-SERVO + HUMAN-WATCH + FED-CAL；单任务 A/B。
4. **W4**：`H_c`/增益/延迟扫描；全量干跑；FED-EVAL 汇总。
5. **W5**：正式提交；保留回滚开关。

若允许多次提交：先交安全基线（WLA + P0）锁「更早提交」tie-break，再交 PAIN-FED 版本。若只允许一次：先用单任务通道把 PAIN-FED 打磨到稳定，再交最终版。

## 9. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判第二个模型 | θ 是标定参数非策略；无梯度；同一 checkpoint 哈希；提交材料写清 C1/C2/C3 |
| 联邦被误解为跨队共享 | 公平性/规则风险 | 明确只在本队 N 端口内聚合；只传低维统计；不传图像/权重 |
| 痛点代理不等于失败率 | 错配工程 | 只用它做**排序先验**；用单任务 A/B 更新；不宣称因果 |
| 10 次试次噪声 | 假阳性 | 配对 + 分层 bootstrap；池化同类任务；不报单任务 3pp |
| 腕部手眼外参漂移 | 伺服偏差 | 每机器人一次重投影校准；夹爪 PnP 自标定；误差大关伺服 |
| HUMAN-WATCH 误报 | 频繁停机 | 双阈值 + 连续 K 帧 + 物体位移确认；误报率纳入门 |
| FER 隐私/偏见 | 合规/声誉 | 不做字面 FER；若做头姿，只做几何、不存人脸、不做情绪标签 |
| pivot 语义不一致 | 动作被拒/机器人不动 | 先 A/B；保留全零回退；不猜符号 |
| 评测端 RTT 高 | 伺服带宽不足 | `H_c` 自适应；预测补偿；回退大 chunk |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |

**本轮最值得押注的是 PAIN-ATLAS：先用 33k 成功演示的触点代理 + 单任务通道，把「哪 6–10 个任务的最后 3 厘米最值得修」测出来，再让 CHUNK-SERVO、FED-CAL 和 HUMAN-WATCH 只服务这些任务；没有痛点图谱，任何新模块都只是盲目加算力。**

# 第 1 轮产物 · PAIN-FED 技术报告

> 检索/复核日期：**2026-11-02（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是想法区「PAIN-FED」的工程化产物；不替换第 12 轮 CHUNK-SERVO，而是先修正它的事实前提，再在其外增加「痛点图谱 + 联邦标定 + 人为干扰预警」三层。

## 0. 结论与边界

### 0.1 一句话结论

公开榜单与 runs 页不足以构成失败图谱；33k 成功演示 + 单任务通道可以构成「触点代理」图谱。PAIN-FED 用 **PAIN-ATLAS** 决定把工程投到哪 6–10 个任务，用 **FED-CAL/FED-EVAL** 在多机器人上只聚合低维校准量与配对实验统计（不聚合权重），用 **HUMAN-WATCH** 把「面部表情识别」降级为「人进入工作区」的几何检测，以覆盖 20% 的人为干扰轴。VLA 仍是唯一学习模型。

### 0.2 证据等级

| 等级 | 含义 | 本报告例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、页面直接核实 | 10 次/任务、5 类泛化、180s、`example_policy.py` chunk=8、腕部内参、WLA `action_horizon=30` |
| B | 我们在公开数据/网页上做的分析，可复现 | 32 数据集 33,276 eps、pivot 统计、episode 0 触点 pilot、runs 页非 10% 整数倍 |
| C | 设计假设，需 G0–G7 验证 | `priority` 与增益 Spearman≥0.5、跨机器人方差降 30%、HUMAN-WATCH 误报≤5% |

### 0.3 本轮不做什么

- 不做字面面部表情识别（相机/分辨率/因果链/隐私都不支持）。
- 不做跨队联邦学习或联邦训练 VLA 权重（数据集中公开、规则要求单模型、公平性不可审计）。
- 不做每端口不同策略网络（违反单模型）。
- 不从零训 6B/14B、不做完整世界模型（官方 WLA 已开源基座）。
- 不做力/触觉闭环、6D 物体位姿网络（API 没有 force/tactile；透明/变形不可靠）。
- 不把预览榜单的任务排名当难度表或失败分布。
- 不在 10 次试次上宣称单任务 3pp 显著。

## 2. 问题形式化

### 2.1 评分与噪声

```math
S=\frac{1}{32}\sum_{t=1}^{32}p_t,\qquad
p_t=\frac{1}{10}\sum_{j=1}^{10}y_{t,j},\qquad y_{t,j}\in\{0,1\}.
```

全局标准误（`p≈0.25`）：

```math
\mathrm{SE}(S)\approx\sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

单任务 10 次的标准误：

```math
\mathrm{SE}(p_t)\approx\sqrt{\frac{0.25\times0.75}{10}}\approx 0.137.
```

因此：

- 单任务可分辨粒度约 **10pp**；不要报 3pp 单任务结论。
- 只有池化同类任务（例如 8 个插入类）才能谈 3–5pp 全局效应。
- A/B 必须配对；报告差值 bootstrap CI，而不是两个平均值。

### 2.2 痛点矩阵

```math
P[t,m,g]\in[0,1],\quad
m\in\{F1,F2,F3,F4,F5,F6\},\quad
g\in\{\text{position, distractor, background, unseen, human}\}.
```

其中失败模式：

| 代号 | 含义 | 典型观测 |
|---|---|---|
| F1 | 识别/语义错误 | 拿错物体、选错目标、语言理解错 |
| F2 | 接近/抓取失败 | 夹空、夹偏、夹爪张不开、滑落 |
| F3 | 搬运/碰撞 | 路径撞物体、掉件、超工作空间 |
| F4 | 接触/插入(<3cm) | 插不进、挂不上、叠不稳、拉链咬合失败 |
| F5 | 人为干扰 | 人移动物体/拿走目标/进入工作区 |
| F6 | 超时/长程 | 180s 内未完成、反复重试 |

派生：

```math
q_t=\frac{\sum_g P[t,F4,g]}{\sum_{m,g}P[t,m,g]},\qquad
\mathrm{priority}_t=\frac{q_t\,\Delta_t}{\mathrm{cost}_t}.
```

### 2.3 联邦标定的可辨识性

设端口 `i` 的真实校准为 `θ_i*`，观测量为：

- 重投影误差 `r_ij = π(δT_head, X_j) - u_ij`；
- 伺服阶跃响应 `e_i(t)`；
- 端到端延迟 `τ_i`（时间戳互相关）；
- 夹爪开合极限 `g_i`。

闭式/稳健估计：

```math
\hat\theta_i=\arg\min_\theta \sum_j \rho\!\left(\|\pi(\theta,X_j)-u_j\|^2\right)
```

其中 `ρ` 为 Huber/Tukey 稳健损失，避免异常帧/遮挡污染。**不做梯度训练**；`θ` 维度 ≤17，样本量（每任务几十帧）足够。

可辨识条件：

1. 每机器人至少 2 个任务、每任务 ≥20 个有效重投影点；
2. 相机外参修正 `δT` 与夹爪偏移 `g` 不共线（需要至少一次腕部旋转/平移激励）；
3. 延迟 `τ` 的估计需要时间戳对齐，误差 ≤30ms；
4. 若某机器人标定协方差过大 → 回退全局 `θ_global`，不强行个性化。

### 2.4 人为干扰的检测模型

把「人进入工作区」写成二分类：

```math
s_t = w_1\,\mathrm{motion}_t + w_2\,\mathrm{hand}_t + w_3\,\mathrm{disp}_t + w_4\,\mathrm{headpose}_t
```

- `motion_t`：头部图像工作区 ROI 的帧差/光流能量（归一化）；
- `hand_t`：运动连通域 + 肤色/形状先验（经典 CV）；
- `disp_t`：GEO-RESIDUAL 的物体位移残差；
- `headpose_t`：若人脸/头可见，头朝向工作区的角度（弱先验，可选）。

决策：

```text
if s_t > θ_hi for K consecutive frames:      APPROACH
elif s_t > θ_lo and disp_t > θ_disp:          HOLD_SAFE
```

双阈值 + 连续帧 + 物体位移确认，降低误报。**不做情绪分类**；`headpose` 只做几何，不存人脸、不打情绪标签。

## 3. PAIN-ATLAS 设计

### 3.1 触点代理指标

对每个 episode 计算（30 fps，`dt=1/30`）：

```text
flips      = #{t : closed[t] != closed[t-1]},  closed = gripper < 1.0
close_frac = first_close_index / N
slow       = #{t : ||v_ee[t]|| < 0.02 m/s} / (N-1)
d5         = #{t : ||p_ee[t] - p_ee[N-1]|| <= 0.05 m} / N
curv       = path_length / max(||p_ee[N-1]-p_ee[0]||, eps)
v_min_near = min speed in last 20% frames
```

这些不是失败率，是「任务在哪里承诺」的代理。与任务语义、单任务 A/B 结合后才变成 `P[t,m,g]`。

### 3.2 Pilot 结果（episode 0，2026-11-02）

用 `datasets-server.huggingface.co/rows` 分页读取，每页 100 帧，直到 episode 改变。结果：

|---|---:|---:|---:|---:|---:|---:|---|
| HangCup | 214 | 7.1s | 2 | 16.9% | 8.4% | 8.3 | 完整 |
| StackBowls | 480 | 16.0s | 2 | 49.9% | 13.1% | 41.4 | 完整 |
| ZipUp | 513 | 17.1s | 6 | 38.9% | 6.6% | 146.3 | 完整 |
| DisconnectEthernet | 405 | 13.5s | 6 | 30.0% | 4.7% | 13.9 | 完整 |
| FoldTowel | ≥700 | ≥23.3s | 4 | 14.4% | 22.4% | 31.2 | 分页上限截断 |
| OrganizeTools | ≥700 | ≥23.3s | 2 | 12.4% | 14.6% | 15.4 | 分页上限截断 |

### 3.3 一个反直觉的排序结果

用 32 个 `stats.json` 构造粗糙运动承诺分数：

```text
MCP = z(duration) + z(pivot_height_range) + z(pivot_yaw_range) + z(base_xy)
    + z(gripper_range) + z(ee_span) + z(lower_body_span)
```

排序头部：

```text
OrganizeTools, StorePaddle, FoldTowel, PackDoll, OrganizeBookshelf,
ToolboxStorage, PackBag, StoreCups, ZipUp, PlugInEthernet
```

排序底部：

```text
PlugCharger, StackBowls, RemovePinnedNote, PourOutMedicine, DisconnectEthernet
```

第 12 轮的 19 个 A 档（接触优先）平均 MCP **-0.76**；13 个 B 档（VLA 优先）平均 **+1.12**。

**结论**：运动承诺与接触痛点**方向相反**。不能把「任务长/动得多」当难度；必须用 `q_t`（F4 占比）而不是 MCP 来分诊。

### 3.4 采集协议（可复现）

1. **元数据层**：32 个 `meta/stats.json`（每个约 80KB），计算 pivot/夹爪/EE/下身体范围；只用于任务画像，不用于失败率。
2. **轨迹层**：优先用 `datasets-server/rows` 分页，避免下载 9GB parquet；每任务抽 3–5 个 episode（不同 session/物体/背景），每 episode 逐帧取 `gripper`、`ee_pose`、`lower_body`、`pivot`。
3. **失败层**：单任务通道记录失败阶段（F1–F6）、失败时的 `d_t`、`flips`、`human_score`、耗时。
4. **更新**：每 3–5 个任务更新一次 `P`；正式评测后只回填聚合统计，不把 10 次试次当 100 次。

### 3.5 分诊输出

```text
for each task t:
    q_t = F4 mass / total mass
    Δ_t = paired A/B gain (single-task channel)
    cost_t = engineer-days + eval slots
    priority_t = q_t * Δ_t / cost_t
sort desc; take top 6–10; freeze the rest at baseline
```

规则：

- `q_t` 高、`Δ_t` 高 → 投 CHUNK-SERVO + DG-KEYFRAME；
- `q_t` 低、`Δ_t` 高 → 可能是背景/干扰物/语义收益，改投 VLA 数据增强，不投伺服；
- `q_t` 低、`Δ_t` 低 → 不投，保留基线；
- `q_t` 高、`Δ_t` 低 → 先查感知/标定，不要加大模型。

## 4. FED-CAL / FED-EVAL 设计

### 4.1 参数化

```python
theta_i = {
  "dT_head":        6,   # 头相机外参修正 (xyz + rotvec)
  "dT_wrist_left":  6,
  "dT_wrist_right": 6,
  "kp":             1,
  "kd":             1,
  "tau_ms":         1,
  "grip_off_l":     1,
  "grip_off_r":     1,
}  # 共 23 维；可裁剪到 12 维（只保留最敏感项）
```

**不是**策略网络，**不是**适配器，**不是** LoRA；是标定/控制参数。

### 4.2 估计（每端口，CPU）

```python
def estimate_calibration(episodes, global_theta):
    # 1) 外参：稳健重投影最小二乘
    dT = huber_lm(residuals=reprojection, init=global_theta["dT"])
    # 2) 增益/延迟：阶跃响应拟合
    kp, kd, tau = fit_step_response(episodes, init=global_theta)
    # 3) 夹爪：开合极限
    grip = estimate_gripper_limits(episodes)
    return theta_i
```

- 全部闭式/迭代最小二乘，不调用 `loss.backward()`；
- 每端口独立，不共享图像/轨迹；
- 估计失败（协方差大/样本少）→ 直接用 `global_theta`。

### 4.3 聚合（服务器）

```python
def aggregate(thetas):
    # 稳健中心
    center = median(thetas, axis=0)
    # 个体偏移限幅
    return [center + clip(t - center, -delta, +delta) for t in thetas]
```

为什么用 median/trimmed mean：

- N 台机器人中可能有一台标定坏/相机脏；均值会被拉偏；
- 低维参数，聚合成本可忽略；
- 不需要 secure aggregation，因为不涉及隐私数据；若未来要跨队，才需要。

### 4.4 FED-EVAL：分层 bootstrap

```python
def federated_eval(records, B=5000):
    # records: (robot, task, pair_id, y_off, y_on)
    deltas = []
    for b in range(B):
        robots = resample(unique_robots(records))
        rs = concat(records[r] for r in robots)
        tasks = resample(unique_tasks(rs))
        ts = concat(rs[t] for t in tasks)
        pairs = resample(ts)
        deltas.append(mean([p.y_on - p.y_off for p in pairs]))
    return percentile(deltas, [2.5, 97.5])
```

报告：

- 全局配对差值 + 95% CI；
- 按失败模式池化的差值（F4 池、F5 池）；
- 按机器人分层的差值，检查是否有单机器人异常；
- 不以单任务 5 次 A/B 宣称显著。

### 4.5 合规边界

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线 | 只用离线统计更新 `P`；线上 VLA + 固定控制 | 最低 | 保守首选 |
| C2 确定性控制器 | 伺服/标定/检测都是几何或统计，无学习权重 | 低 | 主推 |
| C3 同 checkpoint 特征 | 若需描述子，用 VLA 同一 checkpoint 的 encoder | 低–中 | 需要时用 |
| 禁止 | 第二策略网络、LoRA/适配器、跨队权重聚合 | 高 | 不做 |

**审计清单**：

- 所有端口 `sha256(checkpoint)` 一致；
- `theta_i` 维度 ≤17，估计过程无 `backward()`；
- 提交材料写清「VLA 是唯一学习模型；其余为标定/控制/统计」；
- 保留 `PAIN_FED=off` 的回滚开关。

## 5. HUMAN-WATCH 设计

### 5.1 输入与特征

```python
obs = {
  "head_left":  HxWx3, "head_right": HxWx3,
  "wrist_l":    HxWx3, "wrist_r":    HxWx3,
  "ee_l": 6, "ee_r": 6, "grip_l": 1, "grip_r": 1,
}
```

工作区 ROI：用 `state_d435` + 桌面平面先验，把头图的下半部分/桌面区域裁出来；不做全图检测。

特征（CPU）：

```text
motion  = mean(|I_t - I_{t-1}|) in ROI / 255
hand    = max connected component area of motion mask with skin/shape prior
disp    = GEO-RESIDUAL object displacement (m)
headpose= optional; only if face/head detected; angle toward ROI
```

### 5.2 状态机

```text
WATCH:
  if human_score > θ_hi for K frames -> APPROACH
  elif human_score > θ_lo and disp > θ_disp -> HOLD_SAFE

APPROACH:
  hold current EE / slow to 0.2x
  if human leaves ROI and target visible -> RELOCALIZE
  if object moved -> RELOCALIZE -> RESUME/REPLAN
  if timeout -> FAIL_GRACEFUL

HOLD_SAFE:
  freeze gripper, retract 2cm along approach axis
  wait for stable scene (motion < θ_stable for M frames)
  -> RELOCALIZE

RELOCALIZE:
  re-estimate target pose from head stereo
  if valid -> RESUME with conservative gain
  else -> REPLAN (VLA with new image + language)

RESUME:
  blend back over 5 steps; no sudden jump
```

### 5.3 延迟与误报

- 目标：检测 ≤200ms（约 6 帧 @30fps）；
- 误报：≤5%（在无人干扰的正常 episode 上）；
- 漏报：接受，但不能导致碰撞；漏报时回退到 GEO-RESIDUAL 的事后恢复；
- 成本：CPU 光流/帧差，单端口 <10% 一核；不抢 GPU；
- 隐私：不存人脸、不做情绪标签；只保留 `human_score` 与检测框的聚合统计。

### 5.4 与 FER 的关系

- **不做**：情绪分类、表情标签、面部识别；
- **可选 B 级**：头姿/朝向作为弱先验（`headpose`），只在人脸可见时启用；
- **理由**：Hand2Bot（2608.13028）证明表情对 handover 意图有用，但 UniBot 是桌面操作 + 物体位移；域不匹配；头相机分辨率/角度也不保证。

## 6. 系统集成伪代码

### 6.1 `get_action`

```python
class PainFedPolicy:
    def __init__(self, vla, token, control_space):
        self.vla = vla
        self.token = token
        self.control_space = control_space
        self.h_c = 5                 # 先验；单任务通道扫 3/5/8
        self.plan = None
        self.plan_idx = 0
        self.goal = None
        self.theta = load_global_theta()
        self.watch = HumanWatch()
        self.atlas = load_pain_atlas()

    def get_action(self, obs):
        self.watch.update(obs)
        if self.watch.state in ("APPROACH", "HOLD_SAFE"):
            return self.safe_hold(obs)

        self._maybe_request_plan(obs)
        if self.plan is None:
            self.plan = self.vla.predict(obs)   # cold start only
            self.plan_idx = 0

        a_ff = self.plan[self.plan_idx : self.plan_idx + self.h_c]
        mode = self.atlas.mode(task_id=obs.task_id)
        if mode == "SERVO" and self.goal is not None:
            delta = self.servo.compute(obs, self.goal, self.theta)
            a_cmd = compose_relative(a_ff, delta)
        else:
            a_cmd = a_ff

        self.plan_idx += self.h_c
        if self.plan_idx >= len(self.plan):
            self.plan = None
        return self.adapter.to_api(a_cmd, obs, self.token)
```

```python
def reset(self):

```

## 10. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判第二模型 | θ 是标定参数；无梯度；同一 checkpoint 哈希；C1/C2/C3 说明 |
| 联邦被误解为跨队共享 | 公平性/规则风险 | 只在本队 N 端口聚合；只传低维统计；不传图像/权重 |
| 痛点代理≠失败率 | 工程错配 | 只做排序先验；单任务 A/B 更新；不宣称因果 |
| 10 次试次噪声 | 假阳性 | 配对 + 分层 bootstrap；池化同类任务；不报单任务 3pp |
| 手眼外参漂移 | 伺服偏差 | 每机器人复标；夹爪 PnP；误差大关伺服 |
| HUMAN-WATCH 误报 | 频繁停机 | 双阈值 + 连续帧 + 物体位移确认；误报纳入门 |
| FER 隐私/偏见 | 合规/声誉 | 不做字面 FER；头姿只做几何；不存人脸 |
| pivot 语义不一致 | 动作被拒/不动 | 先 A/B；保留全零回退；不猜符号 |
| RTT 高 | 伺服带宽不足 | H_c 自适应；预测补偿；回退大 chunk |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组；相邻帧不跨 split |
| rows API 限流/502 | 数据抽取中断 | 分页重试；缓存；必要时下载 parquet 子集 |
