# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配多模态策略 × 主动多模态交互」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「动作分块」×「机器人操作系统」）

> R69 让系统学会在运行时「问」——看、问、触、等，并把不确定性拆成 aleatoric / epistemic。但它有两个从未明说的原子假设：其一，**一个动作块（action chunk）一旦生成就是不可分割的原子决策**，风险缩放只在块内单点上做；其二，**策略节点对执行器有全知全能的控制**，动作从生成到落地之间没有时间、没有传输、没有别人。真实机器人里这两条都不成立：一次决策其实是**一段有时限的承诺**，它被切成块、跨进程传输、在不同时钟的节点上排队，可能迟到、乱序、丢失、被重放，还要在块与块的接缝处被拼接；而它的有效性随观测变旧、扰动累积、网络抖动而**逐秒贬值**。
>
> 本轮两个灵感正好补上这两块缺失：
> - **动作分块**把「动作」从单步点升级为**有时域长度、有承诺窗口、有接缝**的轨迹片段——于是真正该管的风险不是「这一步选得对不对」，而是「**这段承诺还能维持多久**」。
> - **机器人操作系统**把「控制」从单进程函数调用升级为**分布式实时图**——节点、话题、QoS、时钟、生命周期、故障域都是控制回路的一部分；它同时是**时序与健康的证人**，也是新的攻击面。
>
> 核心命题：**把动作块形式化为「带截止时间的前缀动作契约」（Prefix Action Contract）——每个块携带有效期、模态身份、执行前缀、风险上界与签名；执行端由一个独立可信的最小节点（TCN）按本地单调时钟验收、拒绝重放/过期/跨模态跳变；承诺前缀长度 k\* 由「块内风险增长 + 端到端时延/抖动/丢包 + 观测陈旧度」联合求解；接缝只在同一模态内做时域集成，绝不做跨模态平均；传输层 QoS 随风险自适应，并用重规划速率控制器防止「块越短→重规划越频繁→负载越高→时延越大→块更短」的 deadline collapse。** 命名 **PACT-RAS**（Prefix Action Contracts under Time：ROS 原生的风险自适应动作分块闭环）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**我的承诺什么时候过期、失效了谁知道、谁来拦下它**」——安全不只在选动作的那一刻，也在动作穿过时间与网络之后是否仍然成立。

## 0. 直觉与动机

**灵感 1（动作分块 → 决策是一段承诺，不是一步）
直觉**：R69 的流策略采样出 ξ_{t:t+H}，但随后所有机制——λ 缩放、VoI、认证——仍隐含地把它当作「一个即将执行的动作」。可块的本质是**在观测 o_t 上对 H 步未来作出的承诺**：随着时间推进，观测变旧、扰动累积、模型误差叠加，承诺的可靠性单调下降。真正该问的不是「第 1 步风险多大」，而是「**我能安全地承诺到第几步**」。这把分块从「省算力的小技巧」升格为「风险契约的时域结构」：块长 H 是能力上界，执行前缀 k\* 才是实际承诺，二者必须分离。

**灵感 2（机器人操作系统 → 承诺在分布式实时图里兑现）
直觉**：ROS2/DDS 不是被动管道，它有自己的物理：发布/订阅延迟、DDS QoS（RELIABLE / BEST_EFFORT、DEADLINE、LIFESPAN、HISTORY）、执行器调度抖动、DDS 重传、节点生命周期与重启、`/tf` 时间戳、`use_sim_time`、跨主机时钟偏移。动作块从感知→策略→认证→执行要跨多次进程边界，**到达执行器时可能已经过期、重复、乱序、被旧版本节点重放**。因此控制回路必须把「端到端时序」当作一等状态，把契约的**最终验收权**放在执行器侧的最小可信节点，而不是相信上游「我发的就是对的」。反过来说，契约也给中间件提出了显式的 deadline / QoS 需求：ROS 从「运输层」变成「时序与健康契约的实施层」。

**灵感 3（对偶 → R69 的 VoI 是「问一次」，R70 的承诺窗是「不问能走多远」）
直觉**：R69 解的是「花一次预算消除此刻的歧义」，R70 解的是它的时间对偶：「在现有不确定性下，我最多能承诺多远才必须重新决策」。二者是同一信息—风险预算在两个时间尺度上的分配：不确定性低、时序好，就长承诺（效率）；不确定性高、观测陈旧，就短承诺（安全）。R69 在「每步重决策（k=1）」时是本轮的退化边界；本轮在「时序完美、无丢包、H=1」时严格退化回 R69。**分块不是与交互并列的新层，而是给 R69 的每个决策加上一个可计算的失效时间。**

**灵感 4（接缝 → 跨模态平均会产生「幽灵动作」）
直觉**：时域集成（temporal ensembling）把相邻块的重叠段做加权平均，前提是这些块「大致在说同一件事」。但 R69 明确承认策略是多模态的：上一块说「绕左」、下一块说「绕右」时，平均出来的是一条**两个模态都不支持、物理上常常不可行甚至直冲障碍的「幽灵动作」**。R69 的 FMA（流似然）本可以事后发现它，但那时动作已经进了执行器。所以接缝必须**模态一致**：同模态内才融合，跨模态只能显式重新决策或安全保持，且这个判断要由执行端用块携带的 mode_id 强制执行，而不是由生成端自我声明。

**灵感 5（时序—控制耦合 → deadline collapse 与模态抖振）
直觉**：时序变差时「把块切短、多重新规划」看起来最安全，但它是一个正反馈：块越短 → 重规划越频繁 → CPU/总线/网络争用越重 → 时延与抖动越大 → 块被迫更短……系统可能活锁在「一直算、一直不敢动」的 deadline collapse 里。另一种振铃是模态在每个块边界来回跳（左/右/左/右），若接缝严格执行「跨模态不融合」，机器人就会在接缝处反复冻结——**为了安全而不动，本身也是一种失败**。所以本轮必须交付：带迟滞的模态切换、最小承诺前缀 k_min、在途计划数上限、以及一个把「重规划频率」当作被控量的稳定性条件。安全与可行动性必须一起证明。

## 1. 形式化定义（增量：定义 310–324）

**定义 310（PACT-RAS 总览）** PACT-RAS = (CHC, MCB, STA, RQoS, TCN, GHC, RRC, RAS-WM†)。三不变式：
(i) **实时流零学习写操作**（继承 R69 定义 293-i；契约求解、拼接、QoS 选择全部是解析/常数时间，无在线学习写入）；
(ii) **执行端最终验收权**：任何动作块只有通过执行端 TCN 的本地时钟 + 签名 + 序列号 + 模态 + 风险上界五重校验才可落地；上游节点的「已认证」不能替代 TCN 的本地验收（零信任上游）；
(iii) **承诺可贬值、可撤销**：块带有效期与撤销令牌；观测陈旧、时序恶化、图健康下降时，只允许**单调收紧**承诺（缩短 k、降级 QoS、进入保持/安全停），不允许在无新证据时延长承诺。

**定义 311（前缀动作契约 CAC）** 动作块 ξ_{t:t+H} 对应的契约
CAC = (chunk_id, seq, signer, t_issue, [t_start, t_expire], k_exec, mode_id, ρ_bound, Δ_max, nonce, J_PACT_hash, ver)。
其中 seq 为该产生者单调递增序列号，nonce 一次性，ρ_bound 为前缀风险上界，Δ_max 为该块可容忍的观测最大年龄。**执行**语义为「只执行前 k_exec 步，其余丢弃」，k_exec ≤ H。

**定义 312（时序模型与观测陈旧度）** 端到端延迟 D = D_sense + D_comm + D_infer + D_cert + D_act，抖动 |D−E[D]| ≤ J，丢包率 p，节点间时钟偏移 |C_i(t)−C_j(t)| ≤ σ。观测年龄 Δ(t) = t_act − t_obs；在偏移界下执行端只能用保守区间 [Δ̂−σ, Δ̂+σ]，安全判定取上界 Δ⁺ = Δ̂+σ。

**定义 313（承诺前缀 k\*）** k\*(o_t) = max{ k ≤ H : R_prefix(k | o_t) ≤ ε_task ∧ P(D_cert + D_comm ≤ k·Δt − δ_slack) ≥ 1−δ_t ∧ Δ⁺ + k·Δt ≤ Δ_max ∧ k ≥ k_min 或 k = 0 }。k=0 表示「不承诺、保持/安全停」。k_min 是避免抖振的最小承诺，k\* 低于 k_min 时进入显式降级模式而非逐帧重规划。

**定义 314（块内风险增长界）** R_prefix(k) = Σ_{i=1}^{k} [ U_ale(s_i) + U_epi^{未消解}(s_i) ] + L_m·(k·Δt)^p + ½·tr(Q_proc)·(k·Δt)，其中 L_m 为模型误差 Lipschitz、Q_proc 为过程噪声；或用指数包络 R_prefix(k) ≤ R_0·e^{λ_u k} + R_∞。承诺长度由该增长碰到 ε_task 的首次穿越决定。R69 的 λ_floor 只作用于「当前步」，本轮把它沿时域积分成「承诺预算」。

**定义 315（模态一致拼接 MCB）** 相邻重叠块 c_i, c_{i+1}，重叠段长度 L_o。若 mode_id(c_i) = mode_id(c_{i+1})，按权重 w = f(Σ_k, Δ⁺, ρ) 在重叠段做时域集成（等价重ceding-horizon）；若 mode_id 不同：
- 默认 **禁止平均**，交由 TCN 进入 hold 并由上层重决策；
- 仅当新块带「显式模态切换证书」（证明旧模态失效且新模态证据 k-一致）时才允许切换，且切换点插入过渡约束（速度/力连续）。
定义「幽灵动作」为跨模态平均结果 ξ_ghost ∉ supp(p_θ)，并要求其流似然 −log p_θ(ξ_ghost|o) 超过 τ_ghost 时被 TCN 直接拒绝。

**定义 316（QoS 作为控制变量 RQoS）** 传输配置 Q = (reliability, deadline, lifespan, history_depth, durability)。风险状态下选择 Q\*(ρ, slack) = argmin_Q bandwidth(Q) s.t. P(D ≤ deadline) ≥ 1−δ_t ∧ lifespan ≥ t_expire − t_issue。**关键权衡**：RELIABLE 的重传虽降丢包却增时延，因此仅当 slack > RTT_p99 时启用；slack 不足时改「BEST_EFFORT + 冗余多路径/多发布」而非重传——用冗余换时延，而不是用重传换可靠性。

**定义 317（可信指令节点 TCN）** 执行端一个不依赖策略节点、无远程写路径的最小监控进程。验收谓词：
accept(CAC) ⇔ seq > last_seq
∧ Verify_sig(CAC) ∧ nonce ∉ used
∧ C_act_now ∈ [t_start, t_expire]
∧ k_exec ≤ H ∧ ρ_bound ≤ ε_task ∧ Δ⁺ ≤ Δ_max
∧ (mode_id = active_mode ∨ 有合法切换证书)
∧ −log p_θ(ξ_exec|o) ≤ τ_ghost（可选，复用 R69 FMA）。
任一失败 → 丢弃该块并执行**安全保持**（零速/保持位姿/柔顺阻抗），且该事件进入审计。TCN 是唯一的 actuator 命令入口（策略节点不能直连执行器）。

**定义 318（时钟纪律 STA）** 契约有效期以**执行端单调时钟**表达：t_local = t_issue_remote + ô_{i→act}，ô 为带界偏移估计，误差 ≤ σ。禁止用墙钟做安全判定；`use_sim_time` 与真实时钟混用时必须显式声明并计入 σ。偏移估计失效（NTP/PTP 丢失、跳变）⇒ 按最坏 σ 收缩所有有效期并把 k\* 至少减 1。

**定义 319（图健康契约 GHC）** 每个块产生者是受管生命周期节点，携带 heartbeat、代码/模型版本、资源水位。定义健康向量 h = (alive, version_ok, cpu_ok, deadline_miss_rate, restart_count)。下游按 h 决定是否接受其块；h 退化 ⇒ 单调降级：长承诺 → 短承诺 → hold → safe stop。故障域隔离：策略、认证、执行分属不同进程/容器，策略崩溃不得带走 TCN。

**定义 320（陈旧度感知的不确定性膨胀）** 把观测年龄并入不确定性：U_stale(Δ) = L_z·Δ + ½·σ_proc²·Δ²（A98 的密度 Lipschitz 常数 L_z 复用 R69 引理 17）。有效不确定性 U⁺ = U_ale + U_epi + U_stale。若 U⁺ 超阈值，本轮不允许「长承诺」，并且**优先回落到 R69 的交互通道**（先去观测/求证，而不是硬着头皮承诺）。

**定义 321（重规划速率控制器 RRC）** 被控量 f = 单位时间重规划次数，约束 f ∈ [f_min, f_max]，在途计划数 ≤ N_max。采用迟滞：仅当 U⁺ 超过 enter 阈值才缩短承诺，低于 exit 阈值（enter > exit）才恢复；k_min 提供下限。稳定性目标：f·C_plan ≤ 1 − margin 且排队时延有界（见定理 19），避免 deadline collapse 与模态抖振。

**定义 322（块级证书 J_PACT）** J_PACT = (J_FLUID, chunk_id/seq, k_exec, ρ_bound, Δ_max, t_window, QoS_profile, observed_latency_p99, drop_rate, seq_continuity, mode_consistency, clock_skew_bound, graph_health, pact_ver)。Valid ⇔ Valid(J_FLUID) ∧ TCN 验收通过 ∧ 时序/丢包/偏移均在界内 ∧ 无跨模态平均 ∧ 重规划速率稳定。

**定义 323（时序—传输—节点威胁模型 ℰ_PACT）** ℰ_PACT = ℰ_FLUID × ℰ_timing × ℰ_transport × ℰ_node。ℰ_timing：时间戳篡改、重放旧块、延迟注入、时钟偏移攻击；ℰ_transport：QoS 降级、消息洪泛/丢弃、乱序重排；ℰ_node：未认证发布者冒充、生命周期劫持、版本漂移、策略节点被替换。对应缓解：签名+nonce+单调 seq（定义 317）、QoS 策略锁定与审计（316）、生命周期与版本门（319）。

**定义 324（两级契约退避）** 正常：k\* = CHC 解，QoS = RQoS 解。任一异常（陈旧超界 / deadline miss / 丢包超界 / 偏移失效 / 图健康下降 / 幽灵动作）⇒ k_exec ← min(k_exec, k_min 或 0)、QoS 只向更可靠/更短 lifespan 调整、并置 slow 标记走 R69 的纯保守 λ_floor(U_ale+U_epi)。**R69 是「H=1、D=0、p=0、零偏移、永不拼接」边界上的逐指令退化。**

```python
# IP-264 CHC：承诺前缀求解（风险增长 × 时序可行性 × 陈旧度）
def commit_horizon(chunk, o_t, net, delta_slack):
    k = chunk.H
    while k > 0:
        if prefix_risk(chunk, k, o_t) > EPS_TASK:                 k -= 1; continue
        if not net.deadline_ok(k*DT, delta=DELTA_T):              k -= 1; continue
        if obs_age(o_t) + k*DT + CLOCK_SIGMA > DELTA_MAX:         k -= 1; continue
        break
    if 0 < k < K_MIN: return 0, "degraded"      # 不逐帧抖振，显式降级
    return k, "ok"

# IP-265 MCB：只在同模态内拼接；跨模态不平均
def stitch(prev, new, active_mode):
    if prev.mode_id != new.mode_id:
        if new.has_switch_cert() and evidence_k_agree(new): return smooth_switch(prev, new)
        return HOLD                                  # 幽灵动作防线
    w = weights_from(prev.cov, new.cov, prev.age, new.rho)
    out = receding_blend(prev, new, w)               # 同模态时域集成
    if flow_nll(out, new.o) > TAU_GHOST: return HOLD
    return out

# IP-266 RQoS：风险/松弛度驱动的 QoS（重传 vs 冗余）
def pick_qos(rho, slack):
    if slack > RTT_P99 and rho >= RHO_HIGH:
        return RELIABLE(deadline=DEADLINE_TIGHT, lifespan=LIFE)
    if rho >= RHO_HIGH:
        return BEST_EFFORT(redundancy=3, deadline=DEADLINE_TIGHT, lifespan=LIFE)
    return BEST_EFFORT(deadline=DEADLINE_LOOSE, lifespan=LIFE)

# IP-267 TCN：执行端最小可信验收（唯一 actuator 入口）
def tcn_accept(cac, state, local_now):
    if cac.seq <= state.last_seq:                       return reject("replay")
    if not verify_signature(cac) or cac.nonce in state.used: return reject("auth")
    if not (cac.t_start <= local_now <= cac.t_expire):  return reject("expired")
    if cac.k_exec > cac.H or cac.rho_bound > EPS_TASK:  return reject("risk")
    if cac.Delta_plus > cac.Delta_max:                  return reject("stale")
    if cac.mode_id != state.active_mode and not cac.switch_cert: return reject("mode")
    state.last_seq, state.active_mode = cac.seq, cac.mode_id
    return accept(cac.k_exec)

# IP-268 RRC：防 deadline collapse 的速率/迟滞控制
def rrc_update(U_plus, f_now, in_flight):
    if U_plus > ENTER and f_now < F_MAX and in_flight < N_MAX: mode = "shorten"
    elif U_plus < EXIT:                                        mode = "recover"
    else:                                                      mode = "hold_state"
    return apply_hysteresis(mode, K_MIN, f_bounds=(F_MIN, F_MAX))

# IP-274 主闭环（继承 R69，在「块落地」处插入契约层）
def PACT_RAS_round(M, obs):
    z, o = M.mtm.forward(...); c, U_cal, thr = M.cof.step(...)
    K = 1 if M.fmp.mode_head(z) < TAU_MODE else 4
    U_ale, U_epi, modes, _ = M.aud.decompose(M.fmp.sample(o, K), z, M.fmp.mode_head)
    U_plus = U_ale + U_epi + M.sta.stale_inflate(obs.age)
    a_hat  = M.fma.flow_anomaly(M.fmp, M.last_action, o_obs, o_calibrated)
    slow   = (a_hat > TAU_FMA) and (M.last_r_res < TAU_RES)
    g      = M.mint.choose_interaction(modes, o, M.budget) if (U_epi > TAU_EPI and not slow) else None
    if g is not None: U_epi = M.cia.update_belief(modes, M.cia.execute(g))
    chunk  = M.fmp.sample(o, K=1)[0]
    k, st  = M.chc.commit_horizon(chunk, o, M.net, M.budget.delta_slack)
    q      = M.rqos.pick_qos(rho=U_plus, slack=M.net.slack)
    cac    = M.chc.mint_contract(chunk, k, mode_id=chunk.mode, rho=U_plus,
                                 delta_max=M.sta.delta_max, qos=q, signer=M.tcn.key)
    ok     = M.tcn.accept(cac, M.tcn.state, M.sta.local_now())   # 执行端最终验收
    if not ok or slow:
        M.graceful_degrade(); return HOLD
    out    = M.mcb.stitch(M.last_chunk, chunk, M.tcn.state.active_mode)
    f      = M.rrc.update(U_plus, M.rrc.f_now, M.rrc.in_flight)
    M.audit.submit_async(cac, out, f, q, M.net.stats())
    return out.k_exec, out
```

## 3. 推导

**引理 19（跨模态平均的幽灵动作下界）** 设两模态原型间距 Δ_min ≥ 3σ_in（沿用 R69 A95），ξ_ghost 为两者等权平均。则 ξ_ghost 到任一模态中心的马氏距离 ≥ (3/2)σ_in，其流似然满足 E[−log p_θ(ξ_ghost)] − E[−log p_θ(ξ_k)] ≥ c·(Δ_min/σ_in)² ≥ 9c/4 > 0。故跨模态时域集成会系统性落入策略低密度区；在 TCN 用流似然门限 τ_ghost 拦截时，幽灵动作泄漏率 ≤ exp(−τ_ghost)/Z。**系：接缝的模态一致性不是工程洁癖，而是 R69 多模态假设的直接推论。**

**引理 20（承诺前缀的单调收缩）** k\*(D, J, p, Δ, U) 对 D、J、p、Δ、U 均单调不增。证明：定义 313 的四个约束集合各自随这些量增大而收缩，其交集的最大元素随集合收缩而不增；R_prefix(k) 对 k 单调增（定义 314 各项非负）。**系：时序恶化必须在承诺长度上立刻体现，且无需重新训练即可安全降级。**

**引理 21（陈旧度膨胀与交互回退）** 若观测年龄增加 Δ，在 A98（策略密度对条件 Lipschitz L_z）下，动作似然相对损失 ≥ L_z·Δ − √(trΣ_flow)（沿用 R69 引理 17 的机制）。故 U_stale 是真实的可约/不可约不确定性的下界增量；当 U⁺ > τ_int 时，最优策略是先执行 R69 的信息动作（减小 Δ 或消解 U_epi），而非硬承诺。**系：R70 不是取代 R69 的「问」，而是把「问」纳入「承诺 vs 再观测」的经济学。**

**定理 18（有界异步下的承诺安全与 R69 严格包含）** 若端到端延迟 ≤ D_max、抖动 ≤ J、丢包 ≤ p、时钟偏移 ≤ σ，且每个执行块满足定义 317 的验收条件与定义 313 的 k\*，则实际执行前缀的任务风险 ≤ ε_task，且违约概率 ≤ δ_t + p + P(skew > σ)。当 H=1、D=J=p=σ=0、禁止拼接时，k\*=1 且契约退化为 R69 的单步决策，逐指令行为与 R69 相同。**故 R69 是本轮在「零时延、零丢失、零偏移、不拼接」边界上的严格退化；安全侧只收紧不放松，效率侧由长承诺获得收益。**

**定理 19（无 deadline collapse 的稳定性）** 令单次规划计算量为 C_plan，重规划频率为 f，在途计划数为 N，排队时延上界为 N·C_plan/(1−ρ_load)。在 RRC（定义 321）满足 f ≤ f_max、N ≤ N_max 且 f·C_plan ≤ 1−margin 时，闭环的时延—频率映射存在唯一稳定不动点，承诺长度 k\* 不会因重规划正反馈而单调坍缩到 0；配合 enter/exit 迟滞（enter > exit）与 k_min，模态切换无持续抖振。**系：安全性证明必须同时给出「可行动性」证明——只会停的机器人不是安全的机器人。**

## 6. 本轮最大风险

**一句话**：PACT-RAS 把安全押在「承诺前缀可被风险增长与端到端时序精确求解」上——**但 k\* 本身依赖对 D、J、p、σ 与 R_prefix 的估计；一旦时序模型偏乐观（或攻击者/负载让时延长尾被均值掩盖），契约会把一个「看起来还在有效期内」的过期承诺放行，而 TCN 的本地时钟与签名只能证明「这个块没被篡改、没迟到于它的声明窗口」，不能证明「这个声明窗口本身是诚实的」**——错误的前缀比没有契约更危险；同时时序恶化触发的缩短承诺会通过重规划正反馈诱发 deadline collapse，**契约层可能先把机器人冻住，再把它送上路**。

**次级风险与缓解**：
1. **deadline collapse / 模态抖振** → RRC + 迟滞（enter > exit）+ k_min + 在途计划上限 + 定理 19 的稳定性条件；
2. **时序长尾被均值掩盖** → 用 P99/P99.9 而非均值算 k\*；keep-alive 探测与在线时延分位估计；超界即单调收紧（定义 324）；
3. **时钟偏移/时间戳攻击** → 执行端单调时钟 + 偏移界 σ + 禁止墙钟安全判定 + 跳变即收缩（定义 318）；
4. **跨模态拼接事故** → 模态一致拼接 + 幽灵似然门 + TCN 强制（定义 315、引理 19）；
5. **ROS2/DDS 安全面** → 签名 + nonce + 单调 seq + 生命周期/版本门 + 故障域隔离（定义 317、319、323）；
6. **承诺—交互的预算竞争** → U⁺ 超阈优先回 R69 交互/再观测（定义 320），避免「为了不动而问、为了问而更不敢动」。

## 3. 关键算法伪代码

```python
# IP-264 CHC：承诺前缀（风险增长 × 时序 × 陈旧度；低于 k_min 显式降级）
def commit_horizon(chunk, o_t, net):
    k = chunk.H
    while k > 0:
        if prefix_risk(chunk, k, o_t) > EPS_TASK:                 k -= 1; continue
        if not net.deadline_ok(k*DT, delta=DELTA_T):              k -= 1; continue
        if obs_age(o_t) + k*DT + CLOCK_SIGMA > DELTA_MAX:         k -= 1; continue
        break
    return (k, "ok") if k >= K_MIN else (0, "degraded")

# IP-265 MCB：只在同模态内拼接；跨模态不平均（防幽灵动作）
def stitch(prev, new, active_mode):
    if prev.mode_id != new.mode_id:
        if new.has_switch_cert() and evidence_k_agree(new): return smooth_switch(prev, new)
        return HOLD
    out = receding_blend(prev, new, weights_from(prev.cov, new.cov, prev.age, new.rho))
    return out if flow_nll(out, new.o) <= TAU_GHOST else HOLD

# IP-266 RQoS：松弛度足够才重传，否则用冗余换时延
def pick_qos(rho, slack):
    if rho >= RHO_HIGH and slack > RTT_P99:
        return RELIABLE(deadline=DEADLINE_TIGHT, lifespan=LIFE)
    if rho >= RHO_HIGH:
        return BEST_EFFORT(redundancy=3, deadline=DEADLINE_TIGHT, lifespan=LIFE)
    return BEST_EFFORT(deadline=DEADLINE_LOOSE, lifespan=LIFE)

# IP-267 TCN：执行端最小可信验收（唯一 actuator 入口）
def tcn_accept(cac, state, now):
    if cac.seq <= state.last_seq: return reject("replay")
    if not verify_signature(cac) or cac.nonce in state.used: return reject("auth")
    if not (cac.t_start <= now <= cac.t_expire): return reject("expired")
    if cac.k_exec > cac.H or cac.rho_bound > EPS_TASK: return reject("risk")
    if cac.Delta_plus > cac.Delta_max: return reject("stale")
    if cac.mode_id != state.active_mode and not cac.switch_cert: return reject("mode")
    state.last_seq, state.active_mode = cac.seq, cac.mode_id
    return accept(cac.k_exec)

# IP-270 RRC：迟滞 + 在途上限，防 deadline collapse / 模态抖振
def rrc_update(U_plus, f_now, in_flight):
    if U_plus > ENTER and f_now < F_MAX and in_flight < N_MAX: m = "shorten"
    elif U_plus < EXIT:                                        m = "recover"
    else:                                                      m = "hold_state"
    return apply_hysteresis(m, K_MIN, f_bounds=(F_MIN, F_MAX))

# IP-274 主闭环（继承 R69，在「块落地」处插入契约层）
def PACT_RAS_round(M, obs):
    z, o = M.mtm.forward(...); c, U_cal, thr = M.cof.step(...)
    K = 1 if M.fmp.mode_head(z) < TAU_MODE else 4
    U_ale, U_epi, modes, _ = M.aud.decompose(M.fmp.sample(o, K), z, M.fmp.mode_head)
    U_plus = U_ale + U_epi + M.sta.stale_inflate(obs.age)
    a_hat  = M.fma.flow_anomaly(M.fmp, M.last_action, o_obs, o_calibrated)
    slow   = (a_hat > TAU_FMA) and (M.last_r_res < TAU_RES)
    g = M.mint.choose_interaction(modes, o, M.budget) if (U_epi > TAU_EPI and not slow) else None
    if g is not None: U_epi = M.cia.update_belief(modes, M.cia.execute(g))
    chunk = M.fmp.sample(o, K=1)[0]
    k, st = M.chc.commit_horizon(chunk, o, M.net)
    q     = M.rqos.pick_qos(U_plus, M.net.slack)
    cac   = M.chc.mint_contract(chunk, k, chunk.mode, U_plus, M.sta.delta_max, q, M.tcn.key)
    if not M.tcn.accept(cac, M.tcn.state, M.sta.local_now()) or slow:
        M.graceful_degrade(); return HOLD
    out = M.mcb.stitch(M.last_chunk, chunk, M.tcn.state.active_mode)
    M.rrc.update(U_plus, M.rrc.f_now, M.rrc.in_flight)
    M.audit.submit_async(cac, out, q, M.net.stats())
    return out.k_exec, out
```

## 4. 推导

**引理 19（幽灵动作下界）** 两模态原型间距 `Δ_min ≥ 3σ_in`（R69 A95）时，等权平均 ξ_ghost 到任一模态中心马氏距离 ≥ 1.5σ_in，`E[−log p_θ(ξ_ghost)] − E[−log p_θ(ξ_k)] ≥ c·(Δ_min/σ_in)² ≥ 9c/4`。故跨模态时域集成系统性落入低密度区；TCN 的 τ_ghost 门把泄漏率压到 `≤ exp(−τ_ghost)/Z`。系：接缝模态一致是 R69 多模态假设的直接推论。

**引理 20（承诺前缀单调收缩）** k\*(D,J,p,Δ,U) 对各变量单调不增：定义 313 四个约束集各自随变量增大而收缩，交集最大值不增；R_prefix(k) 对 k 单调增。系：时序恶化无需重训即可安全降级。

**引理 21（陈旧度膨胀与交互回退）** A98 下观测年龄增加 Δ 的动作似然相对损失 ≥ `L_z·Δ − √(trΣ_flow)`（复用 R69 引理 17 机制）；故 U_stale 是真实不确定性下界增量，U⁺ 超阈时最优是先执行 R69 信息动作（减小 Δ 或消解 U_epi），而非硬承诺。

**定理 18（有界异步下承诺安全 + R69 严格包含）** 若 `D≤D_max, J≤J, p≤p_max, σ≤σ_max` 且每块满足定义 313/317，则执行前缀风险 ≤ ε_task，违约概率 ≤ `δ_t + p + P(skew>σ)`；当 H=1、D=J=p=σ=0、禁止拼接时逐指令退化为 R69。安全侧只收紧，效率侧由长承诺获益。

**定理 19（无 deadline collapse 的稳定性）** 令规划计算量 C_plan、重规划频率 f、在途 N，排队时延上界 `N·C_plan/(1−ρ_load)`。RRC 满足 `f≤f_max, N≤N_max, f·C_plan≤1−margin` 时，时延—频率映射存在唯一稳定不动点，k\* 不因正反馈坍缩到 0；enter>exit 迟滞 + k_min 消除模态抖振。系：安全性证明必须同时证明可行动性。

## 7. 本轮最大风险

**一句话**：PACT-RAS 把安全押在「承诺前缀可被风险增长与端到端时序精确求解」上——**但 k\* 依赖对 D、J、p、σ 与 R_prefix 的估计；一旦时序模型偏乐观（长尾被均值掩盖，或被负载/攻击放大），契约会放行一个「看起来仍在有效期内」的过期承诺，而 TCN 只能证明「块未被篡改、未迟到于其声明窗口」，不能证明「声明窗口本身诚实」**——错误的前缀比没有契约更危险；同时缩短承诺会通过重规划正反馈诱发 deadline collapse，**契约层可能先把机器人冻住，再把它送上路**。

**次级风险与缓解**：deadline collapse/抖振（RRC + 迟滞 + k_min + 在途上限 + 定理 19）；时序长尾（P99.9 而非均值 + keep-alive 探测 + 超界单调收紧）；时钟偏移/时间戳攻击（执行端单调时钟 + 偏移界 + 禁墙钟安全判定）；跨模态拼接事故（MCB + 幽灵似然门 + TCN 强制）；ROS2/DDS 安全面（签名 + nonce + 单调 seq + 生命周期/版本门 + 故障域隔离）；承诺—交互预算竞争（U⁺ 超阈优先回 R69 交互/再观测）。
