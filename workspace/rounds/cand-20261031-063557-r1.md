# 第 13 轮（新循环第 1 轮）· DR-TAC：域随机化漏掉的域是「时间」——把延迟条件写进 action head，把仿真训练降级为延迟反事实，把低延迟推理做成 AoI 风险调度

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新灵感循环第 1 轮，研究线承接第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO。三个灵感词是「域随机化」「仿真训练」「低延迟推理」。本轮不推倒 CHUNK-SERVO 的「30 步规划 + 5 步伺服」，而是补它默认掉的一层：**CHUNK-SERVO 把执行层闭环了，但策略仍是在「零延迟、同步时钟」的演示上训练的。**

## 0. 先给结论：第 12 轮把反馈周期压到 167ms 执行块（含 RTT 约 200–320ms），却把训练-部署的时间差留在了模型里

第 12 轮 CHUNK-SERVO 的三件事——30 步 VLA 规划、5 步视觉伺服、演示检索相对目标——都建立在一个没有被写出来的假设上：

> **训练时的 `o_t → a_t` 与部署时的 `o_t → a_t` 是同一个条件分布。**

真实系统不是。部署时策略看到的是 `o_{t-δ}`，却要输出从 `t` 开始执行的动作；`δ` 包含图像采集、JPEG 编码、广域网 RTT、排队、推理和动作下发，可能是 20ms，也可能是 300ms，而且随时间抖动。策略在演示里学的条件概率是 `p(a_t | o_t)`，部署时被强行当成 `p(a_t | o_{t-δ})` 使用。这不是视觉域偏移，也不是物理域偏移，而是**时间域偏移**。

这个偏移的量级恰好致命：

- 夹爪以 5cm/s 接近，100ms 的观测年龄对应 **5mm** 的系统性前馈误差；
- 以 10cm/s 接近，对应 **1cm**；
- 以 20cm/s 接近，对应 **2cm**。

最后 3 厘米的插入、挂杯、拉拉链、开锁，误差预算本来就只有几毫米。伺服可以修正，但它是在和一个**有偏的前馈**对抗：前馈越偏，伺服修正越大，越容易饱和、超调、振荡；而伺服自己也在延迟链路里。

所以本轮的押注是 **DR-TAC**（Domain-Randomized Time-Aware Chunking）：

> **把「时间」当成一个需要随机化的域：训练时随机采样观测延迟、动作延迟、chunk 长度和去噪深度，用执行时刻对齐的目标训练同一个 action head；用延迟在环的仿真生成反事实样本并校准一张风险表；在线用计划年龄（AoI）、去噪深度和伺服增益做风险约束下的刷新调度。仍然只有一个学习模型，伺服仍然是无学习权重的确定性控制器。**

一句话：**第 12 轮把「1 秒开环」变成「167ms 执行块闭环」；第 13 轮要把「策略在零延迟里训练、在随机延迟里执行」变成「策略在随机延迟里训练、在风险约束下执行」。**

三个可验证创新点：

1. **TDR（Time-Domain Randomization，时间域随机化）**：训练时对 `(δ_o, δ_a, H, k)` 采样，目标从 `a_t` 改成执行时刻的 `a_{t+δ_eff}`；让模型学 `p(a_{t+δ_eff} | o_{t-δ_o}, δ_eff, H, k)`。用 G8 验证：在 100ms 延迟回放上，动作误差至少降 30%，名义条件不回退。
2. **LIS（Latency-In-the-loop Simulation，延迟在环仿真）**：数字孪生不再只标定相机/增益，而是把 API 的延迟队列、抖动、丢帧、多端口排队都建进去；在域随机化下生成延迟反事实，并校准 `(任务族, 相位, δ, H, k, 计划年龄) → 失败风险` 的表。用 G9/G10 验证：仿真风险排序与真机单任务失败排序 Spearman ≥0.6，风险表校准误差 ≤0.1。
3. **AIC（Age-of-Information aware Anytime Chunking，计划年龄感知的 anytime 调度）**：`action_chunk_size` 是提交时固定的，在线不能改 H；能改的是 VLA 刷新深度 `k`、刷新时机、以及伺服增益。把「计划还有多久过期」当成一等状态，在截止时间前用最小的 `k` 刷新；用 G11/G12 验证：p99 刷新延迟降 ≥25%，接触任务不回归，RTT 0–200ms 下成功率不降。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **域随机化** | 时间域：`δ_o, δ_a, jitter, 丢帧, 控制频率, H, k`；视觉域：光照/纹理/相机位姿；物理域：摩擦/质量/物体位姿 | 不只做像素/物理 DR；不把延迟当成一个固定常数；不假设仿真能预测真机绝对成功率 |
| **仿真训练** | 只微调 action head + 3 维延迟编码器；仿真生成「延迟观测 → 执行时刻动作」的反事实对；冻结 VLM；真实演示锚定 ≥50% | 不从零训 VLA；不做完整 sim-to-real 策略训练；不让仿真数据替代真实数据 |
| **低延迟推理** | 4 步去噪的 anytime early-exit；计划年龄 + 截止时间的刷新调度；共享 GPU 队列的 EDF/least-slack 调度；缓存复用 | 不加载第二个 draft 模型；不做 30Hz 广域网伺服；不假设 `action_chunk_size` 可变 |

## 1. 直觉：三个词其实是一条「时间—数据—预算」链

### 1.1 域随机化：最大的未随机化域，是时钟

域随机化在机器人里通常意味着：随机光照、纹理、相机位姿、摩擦、质量、物体位置。它解决的是 `p(o, s, dynamics)` 的覆盖问题。但 UniBot 的远程 API 还有一个更隐蔽的分布：

```text
t_obs_capture → t_obs_arrive → t_plan_start → t_plan_ready → t_action_execute
        δ_capture+δ_network = δ_o          δ_infer(k)        δ_act
```

演示数据是同步采集的：图像、关节、动作共享一个时钟，`δ≈0`。部署时这条链被拉长，而且每个环节都在抖。策略没有见过「我看到的是 100ms 前的世界，但动作要从现在开始执行」这种样本，所以它会把旧世界的动作原封不动地搬到现在。

**TDR 的核心不是给图像加噪声，而是给时间加噪声。** 对每条演示，取 `o_{t-δ_o}` 和 `s_{t-δ_o}`，把监督目标改成 `a_{t+δ_eff}`，其中 `δ_o` 是计划开始时的观测年龄（含采集、编码、网络、排队），

```math
\delta_{\mathrm{eff}} = \delta_o + \delta_{\mathrm{infer}}(k) + \delta_{\mathrm{act}}.
```

模型学的不是「过去的状态该做什么」，而是「以我延迟看到的世界，等到动作真正执行时，专家会做什么」。这把一个系统性偏差变成了一个可学习的条件变量。

### 1.2 仿真训练：不是训策略，是训「延迟条件」和「风险表」

第 12 轮明确说「数字孪生只做标定/风洞，不训练策略」，理由是对的：sim-to-real gap 会让仿真里学到的策略在真机上失效。但这句话不应该推出「仿真不能参与训练」。正确的区分是：

- **不做什么**：在仿真里从零训一个 6B VLA，或者用仿真数据替代 33k 真实演示；
- **做什么**：用仿真生成**延迟反事实**——同一个任务、同一段轨迹，在随机延迟/随机物理/随机视觉下，执行时刻的状态和动作是什么；用它微调**同一个 action head**，并用真实演示锚定。

仿真的角色从「策略训练场」降级为「延迟风洞 + 反事实数据源 + 风险标定台」。这既利用了仿真能自由控制延迟的优势，又避免了让仿真决定任务语义。若 G9 显示仿真风险排序与真机不一致，直接把 `λ_sim` 降到 0，只保留真实演示上的 TDR；这时方案仍然成立，只是少了反事实覆盖。

### 1.3 低延迟推理：不是「更快」，是「更早决定何时刷新」

第 12 轮把 `action_chunk_size` 设成 5，但 API 的 chunk size 是**提交时固定**的，在线不能每调用改 H。真正能在线调的是：

- VLA 的**去噪深度** `k`（4 步扩散可以早停在 1/2/3 步）；
- **何时刷新** 30 步 plan（计划年龄 `a` 与场景变化）；
- **伺服增益**（按延迟 `d` 降档）。

注意：early-exit 只省「去噪步数」这部分可变成本；VLM 编码、图像预处理、网络传输是固定成本。若固定成本主导，低延迟的主杠杆是**缓存复用 + 刷新时机**，不是把 4 步压到 1 步。所以低延迟推理的正确目标不是「把单次推理压到多快」，而是：

> **在计划过期之前，用最小的去噪深度、最合适的刷新时机，把「够用」的新计划送到执行边界；如果送不到，就让伺服和缓存计划安全退化。**

这把问题从「模型加速」变成了「计划年龄（Age-of-Information）约束下的 anytime 调度」。early-exit 是手段，AoI 是目标，风险表是约束。

## 2. 诊断：第四个「1 秒」在训练集里

第 12 轮诊断了三个「1 秒」：规划 1 秒、推理/网络 0.1–0.3 秒、恢复 1 秒。本轮补第四个：

> **训练-部署的时间差：演示是零延迟的，部署是随机延迟的。**

把误差拆开。设真实状态 `x_t`，专家策略 `π*`，部署策略 `π_θ`：

```math
e_t = \pi^*(x_t) - \pi_\theta(o_{t-\delta_o}).
```

做两项分解（执行延迟 `δ_a` 已吸收进 `δ_eff`，会把目标推得更远）：

```math
e_t =
\underbrace{\pi^*(x_t) - \pi^*(x_{t-\delta_o})}_{\text{时间域偏移/状态漂移}}
+
\underbrace{\pi^*(x_{t-\delta_o}) - \pi_\theta(o_{t-\delta_o},\delta_{\mathrm{eff}})}_{\text{策略/感知/执行误差}}.
```

第一项是**时间域偏移**：即使感知完美、策略完美，只要 `x_t ≠ x_{t-\delta_o}`，用旧状态算出的动作就是错的。它正比于 `v_max δ_o`。第二项才是传统 VLA 在解决的感知/语义误差，外加执行延迟带来的目标错位。

为什么更大的 VLA 不解决第一项？因为第一项是**信息缺失**，不是模型容量不足。`o_{t-\delta_o}` 里没有 `x_t` 的未来信息；再大的模型也只能猜。为什么更长的 chunk 更糟？因为长 chunk 让 `H/f_c` 变大，计划年龄更大，第一项更大，执行延迟也更难被下一个刷新追上。为什么纯视觉伺服不够？因为伺服是在**有偏前馈**上做修正；前馈偏 1cm，伺服就要在 167ms 内补 1cm，容易饱和，而且伺服自己也在延迟里。

**TDR 直接优化第一项**：让模型在训练时就见到「旧观测 → 新动作」的配对，学会补偿。**AIC 优化计划年龄**：让刷新在计划过期前完成，减少「用 1 秒前的 plan 执行现在」的概率。**LIS 优化风险表**：告诉我们什么时候补偿不够、必须降增益/回退。

## 3. 方法草图：三个组件，一个模型

### 3.1 TDR：执行时刻对齐的行为克隆

标准 BC：

```math
\mathcal{L}_{\mathrm{BC}} = \mathbb{E}_{(o_t,s_t,a_t)\sim\mathcal{D}_R}\left[\ell(\pi_\theta(o_t,s_t),a_t)\right].
```

TDR：

```math
\mathcal{L}_{\mathrm{TDR}} =
\mathbb{E}_{\substack{(o,s,a)\sim\mathcal{D}_R\\ \delta_o,\delta_a\sim\mathcal{D}_\delta\\ H\sim\mathcal{H},\,k\sim\mathcal{K}}}
\left[
w(\delta_{\mathrm{eff}})\,
\ell\!\left(
\pi_\theta\!\left(o_{t-\delta_o},s_{t-\delta_o},\delta_{\mathrm{eff}},H,k\right),
a_{t+\delta_{\mathrm{eff}}}:a_{t+\delta_{\mathrm{eff}}+H}
\right)
\right],
```

其中 `δ_eff = δ_o + δ_i(k) + δ_a`，`δ_o` 含网络/排队。关键点：

- **目标按执行时刻对齐**，不是按观测时刻对齐；
- **动作表示要对齐**：WLA 输出的是相对 plan-time 当前 EE 的 delta；TDR 的目标必须先重建演示的绝对 EE 轨迹，再算 `(T^{obs})^{-1} T_{t+δ_eff+i}^{demo}`，不能直接拿演示的原始相对动作，否则会多一个坐标系错位；
- `w(δ_eff)` 做延迟分箱加权，避免长延迟样本被短延迟淹没；
- 保留 20–30% 的零延迟样本，防止名义性能回退；
- 对 4 步扩散加 early-exit 一致性：`π_k ≈ π_K`（`π_K` 停止梯度），让任意 `k` 的输出都可用；
- 延迟编码器只有 3 维输入（`δ_eff, H, k`），2 层 MLP，参数量 <10k，接在 robot-state projector 或 DiT 条件上；VLM 冻结。

为什么这不算第二个模型？因为延迟编码器和 action head 在同一个 checkpoint 里，推理时只有一份权重；它不是策略集成，也不是残差网络，而是**同一个策略的条件输入**。

### 3.2 LIS：延迟在环的仿真，只做三件事

1. **生成反事实对**：在 IsaacLab/MuJoCo 里给同一任务注入随机延迟 `δ_o, δ_a`，渲染 `o_{t-δ_o}`，用特权状态/脚本专家给出 `a_{t+δ_eff}`；这是「延迟观测 → 执行时刻动作」的监督，不是让仿真策略自己学任务。
2. **校准风险表**：对每个 `(任务族, 相位, δ_bin, H, k, 计划年龄 bin)` 跑闭环，统计失败率；用分层 beta-binomial 上界 + sim-real 偏移余量，得到 `\bar R(c)`。
3. **压测调度器**：模拟 N 端口共享 GPU 的排队，测 `δ_infer(k, queue)`，验证 EDF/least-slack 刷新策略在 RTT 0–200ms 下不饿死、不抖动。

域随机化范围分三层：

- **时间**：`δ_o ∈ [0,200]ms`（含网络/排队），`δ_a ∈ [0,50]ms`，jitter ±30ms，丢帧 0–10%，控制频率 20–30Hz；
- **视觉**：光照 0.3–1.5×、色温 4000–8000K、背景纹理 10–20 种、相机位姿 ±2cm/±2°、JPEG 60–95、运动模糊 0–5px；
- **物理**：摩擦 0.2–1.0、质量 0.5–2×、物体位姿 ±3cm/±10°、桌面高度 ±2cm、关节阻尼 0.8–1.2×。

注意：时间 DR 是**训练分布**，不是测试噪声。测试时只测量真实延迟，不人为注入；仿真只用于训练/校准，不用于报告真机成功率。

### 3.3 AIC：固定 chunk，在线调刷新深度与时机

设：

- `H`：提交时固定的 API chunk size（候选 3/4/5/6/8，离线选）；
- `T_c = 1/f_c`：控制周期；
- `H_plan`：VLA 一次输出的 plan 长度（WLA 默认 30 步）；
- `a_m`：第 `m` 个执行边界时，当前 plan 的年龄；
- `δ_i(k)`：去噪 `k` 步的推理延迟（含排队）；
- `δ̂`：观测年龄估计；
- `c`：上下文（任务/相位/场景变化/伺服置信度）。

在线决策不是「选 H」，而是「选刷新动作」：

```math
u_m \in \{\text{reuse},\ \text{refresh}(k=1),\ \text{refresh}(k=2),\ \text{refresh}(k=3),\ \text{refresh}(k=4)\}.
```

约束：

```math
\bar R(c, a_m, \delta_{\mathrm{eff}}(k), H) \le \epsilon,
\qquad
\delta_i(k) + \delta_a \le D_m,
\qquad
K_p H \le \eta\,\kappa^*(d),
```

其中 `D_m = (H_plan - a_m)T_c` 是计划过期前的剩余时间，`d = ceil(δ_eff/(H T_c))` 是延迟块数，`κ^*(d)` 是离散延迟系统的临界增益（第 12 轮给过近似；本轮在产物区给出闭式）：

```math
\kappa^*(d) = 2\sin\!\left(\frac{\pi}{2(2d+1)}\right).
```

选择规则：

- 若计划还新、场景变化小 → `reuse`，不烧 GPU；
- 若计划将过期或场景变化大 → 在截止时间前选**满足风险约束的最小 k**；
- 若没有可行 k → 用 `k=4` 刷新并准备「缓存 plan + 伺服」的过渡块；若仍超时 → 安全 hold；
- 加滞回：节省 <20ms 或风险余量变化 <10% 不切换，避免 k 抖动；
- 人为干扰（`edit_score` 高）→ 强制 `k=4` 刷新 + 降增益。

AIC 的「低延迟」不是让每一步都 1 步去噪，而是让**平均 GPU 占用**下降、**关键刷新**仍然用足够的深度。它把低延迟推理从「模型加速」变成「风险约束下的资源分配」。

## 4. 与第 8/12 轮的关系：保留、升级、剪枝

**保留**：

- CHUNK-SERVO 的 30 步规划 + 5 步伺服 + 演示检索相对目标；
- GEO-RESIDUAL 的接触相位、编辑检测、法向/切向分解；
- 官方 WLA 6B 基座、33k 真实演示、单任务不计分通道；
- 数字孪生只做标定/风洞的纪律。

**升级**：

- 执行层闭环 → **训练层时间闭环**：从「零延迟 BC」升级为「延迟条件 BC」；
- 固定 H=5 的启发式 → **离线 H 选择 + 在线 k/刷新/增益调度**；
- 仿真的角色 → **延迟反事实数据源 + 风险标定台**；
- 低延迟推理 → **AoI/截止时间约束下的 anytime 调度**；
- 伺服增益 → **按延迟块数 `d` 的稳定域调度**。

**剪枝**：

- 不做第二个 draft 模型/残差策略（单模型合规）；
- 不从零训 VLA/World Model（官方 WLA 已开源）；

## 6. 为什么现在做：三个「已经具备」和三个「还没有」

已经具备：

1. **官方 WLA 的 4 步扩散 action head**：early-exit 不需要改架构，只需要暴露中间步；24GB 可微调。
2. **33k 真实演示 + 头双目标定**：TDR 可以在真实演示上直接做，不依赖仿真；相对目标/相位/接触信号已有第 11/12 轮的基础。
3. **官方 IsaacLab/MuJoCo + 提交 API**：延迟队列、多端口、chunk 执行都可以在仿真里复现；单任务不计分通道可以做真机 A/B。

还没有：

1. **据本轮有限检索，尚未见到把「时间域随机化」写成 action chunking 训练目标的公开工作**；现有 delay-aware 工作多针对单步 RL、固定延迟或同步执行，不是「可变 chunk + anytime 推理 + 远程 API」的组合。
2. **据本轮有限检索，尚未见到把「计划年龄」直接接到 VLA 刷新调度的公开工作**；RTC/异步 chunk 工作关注执行重叠，不关注「计划过期风险」与「去噪深度」的联合约束。
3. **据本轮有限检索，尚未见到把「仿真风险排序」与「单模型合规」结合的公开工作**；多数 sim-to-real 工作要么训策略，要么只做视觉 DR，不做时间 DR + 风险表。

这三点合起来，是一个足够具体、可证伪、且不需要第二个模型的增量。

## 7. 本轮最大风险

**当前方案最大的风险是：时间域随机化在仿真/回放里学到的延迟补偿，可能无法迁移到真实网络抖动和多端口排队造成的非平稳延迟上；一旦风险表失准，AIC 会把「更快刷新」变成「更自信地用错计划」。**

### 2.2 时间模型

一次刷新请求的时间线：

```text
capture                  arrive / plan start        plan ready             execute
  │                           │                         │                     │
  ├──── δ_o (含网络/排队) ────►│                         │                     │
  │                           ├──── δ_i(k) ────────────►│                     │
  │                           │                         ├──── δ_a ───────────►│
  ▼                           ▼                         ▼                     ▼
t-δ_o                         t                    t+δ_i(k)            t+δ_i(k)+δ_a
```

取计划开始时刻为 `t`，则观测来自 `t-δ_o`，动作从 `t+δ_i(k)+δ_a` 开始执行；从采集算起的有效延迟是：

```math
\delta_{\mathrm{eff}}(k) = \delta_o + \delta_i(k) + \delta_a.
```

一次 API chunk 的执行时长是 `H T_c`；执行边界为 `t_m = m H T_c`。第 `m` 个边界看到的观测年龄为 `δ_{o,m}`，plan 年龄为 `a_m`。定义：

```math
T_{\mathrm{chunk}}(H) = H T_c + \delta_o \quad\text{(伺服反馈周期)},
```

```math
T_{\mathrm{refresh}}(k) = \delta_o + \delta_i(k) + \delta_a \quad\text{(采集到新 plan 执行)},
```

```math
T_{\mathrm{loop}}(H,k) = H T_c + \delta_o + \delta_i(k) + \delta_a \quad\text{(最坏情况：每个边界都要新 plan)}.
```

刷新可以在当前 chunk 执行期间异步完成；若 `T_refresh(k)` 不超过当前 chunk 的剩余时间，新 plan 能赶上下一个边界；否则下一个边界继续用缓存 plan + 伺服。注意：`δ_i(k)` 只影响**刷新**的截止时间，不影响已缓存 plan 的 chunk 边界；这是本轮与「单次推理延迟」叙事的关键区别。

### 2.3 延迟条件化策略

标准行为克隆学习：

```math
\pi_0(a_t \mid o_t, s_t, \mathcal{G}).
```

部署时实际可用的是：

```math
\pi_0(a_t \mid o_{t-\delta_o}, s_{t-\delta_o}, \mathcal{G}),
```

这是一个**条件错配**。DR-TAC 改为学习：

```math
\pi_\theta\left(a_{t+\delta_{\mathrm{eff}}}:a_{t+\delta_{\mathrm{eff}}+H}
\;\middle|\;
o_{t-\delta_o}, s_{t-\delta_o}, \delta_{\mathrm{eff}}, H, k, \mathcal{G}\right).
```

需要注意：`s` 是模型实际收到的本体状态；若 API 的 state 比图像新，`s` 用最新 state，`δ_o` 只表示图像年龄，风险表分别记录图像年龄与 state 年龄。

延迟条件通过一个 3 维编码器注入：

```math
\phi(\delta_{\mathrm{eff}}, H, k)
=
\mathrm{MLP}\left(\frac{\delta_{\mathrm{eff}}}{\tau_{\max}},
\frac{H}{H_{\max}}, \frac{k}{K}\right)\in\mathbb{R}^{32}.
```

`φ` 加到 robot-state projector 的输出上，或作为 DiT action head 的 FiLM 调制。VLM 冻结；`φ` 与 action head 在同一个 checkpoint 内。训练时 `δ_eff` 从分布采样；部署时用预测的 `δ_eff`（滑动 90 分位而非均值）作为条件，实际延迟偏差由风险表和伺服吸收。

### 2.4 风险约束调度问题

在每个执行边界 `m`，在线策略 `Π` 选择：

```math
u_m \in \mathcal{U}
=
\{\text{reuse}\}\cup\{\text{refresh}(k):k=1,\ldots,K\}.
```

上下文 `c_m=(task, phase, \chi, \delta\text{-bin}, H, age\text{-bin})`。定义：

- 刷新延迟：`T_refresh(reuse)=0`，`T_refresh(refresh(k))=\delta_i(k)+\delta_{\mathrm{net}}`；
- 风险：`R(u,c_m,a_m)` 为执行下一个 chunk 的失败/碰撞/超时风险；
- 稳定性：`κ=K_p H`，`d=ceil(δ_eff/(H T_c))`，要求 `κ≤η κ^*(d)`；
- 截止时间：`D_m=(H_plan-a_m)T_c`，刷新必须满足 `\delta_i(k)+\delta_{\mathrm{net}}≤D_m`，除非选择回退。

在线问题：

```math
\begin{aligned}
\min_{u_m\in\mathcal{U}}\quad & \mathbb{E}[T_{\mathrm{refresh}}(u_m)] \\
\text{s.t.}\quad
& \bar R(u_m,c_m,a_m)\le \epsilon,\\
& K_p H \le \eta\,\kappa^*(d(u_m)),\\
& \delta_i(k)+\delta_{\mathrm{net}}\le D_m \quad\text{or}\quad u_m=\text{fallback}.
\end{aligned}
```

`|\mathcal{U}|=K+1≤5`，枚举即可。计划年龄把问题耦合到未来：刷新太早浪费 GPU，刷新太晚错过截止时间。离线用离散动态规划求阈值策略；在线用阈值表 + 滞回。

### 2.5 统一视角：时间增广的约束 POMDP

把时间变量加入状态，而不是把它们当外部噪声：

```math
\tilde{x}_t=(x_t,\ \delta_o,\ \delta_i(k),\ a_m,\ c_m),
```

其中 `x_t` 是物理状态，`δ_o` 是图像年龄，`δ_i(k)` 是推理/排队延迟，`a_m` 是 plan 年龄，`c_m` 是任务/相位/场景变化上下文。策略看到的是 `(o_{t-δ_o}, s, δ_eff, H, k)`，它近似的是时间增广状态下的 belief-conditional policy：

```math
\pi_\theta(a_{t+\delta_{\mathrm{eff}}}:a_{t+\delta_{\mathrm{eff}}+H}
\mid o_{t-\delta_o},s,\delta_{\mathrm{eff}},H,k,\mathcal{G}).
```

在线调度是有限期约束 POMDP：

```math
\max_{\Pi}\ \mathbb{E}[\mathbf{1}_{\mathrm{success}}]
-\lambda\,\mathbb{E}[T_{\mathrm{loop}}]
\quad\text{s.t.}\quad
\mathbb{E}[R]\le\epsilon,\quad
K_pH\le\eta\kappa^*(d).
```

TDR 训练 belief-conditional policy；LIS 估计风险 `R`；AIC 在 `a_m` 上求解调度。三者共享同一组时间变量 `(δ_o, δ_i, a_m, c_m)`，所以它们是一个算法的三个阶段，不是三个互不相干的技巧。

## 3. 算法 DR-TAC

### 3.1 总览

```text
┌──────────────────────────── Offline ────────────────────────────┐
│ 真实演示 D_R ─┐                                                  │
```

### 3.2 离线阶段 A：TDR 微调

**输入**：真实演示 `D_R`；域随机化仿真 `D_S`；延迟分布 `D_δ`；候选 `H`、`k`；WLA 基座 `θ_0`。

**输出**：延迟条件化 checkpoint `θ*`。

伪代码：

```text
for step in 1..N_train:
    B_R = sample_real(D_R, batch/2)
    B_S = sample_sim(D_S, batch/2)

    for each sample (episode, t) in B_R ∪ B_S:
        δ_o   ~ D_o
        δ_a   ~ D_a
        H     ~ H_candidates
        k     ~ K_candidates
        δ_eff = δ_o + δ_i(k) + δ_a

        o_in  = observation at t - δ_o
        s_in  = proprio at t - δ_o
        target = [(T^obs)^-1 @ T_{t+δ_eff+i}^demo for i in 0..H-1]

        if t + δ_eff + H > T_episode: mask/drop

    L_R = mean( w(δ_eff) * ℓ( π_θ(o_in,s_in,δ_eff,H,k), target ) )
    L_S = mean( w(δ_eff) * ℓ( π_θ(o_in^S,s_in^S,δ_eff,H,k), target^S ) )
    L_con = mean( Σ_{k=1}^{K-1} ℓ( π_k, sg(π_K) ) )
    L_mono = mean( Σ_{k=1}^{K-1} relu( η_k - η_{k+1} ) )
    L = L_R + λ_s L_S + λ_c L_con + λ_m L_mono + λ_r ||θ-θ_0||^2
    θ ← AdamW(θ, ∇L)
```

关键实现细节：

1. **目标按执行时刻对齐**。不是 `a_t`，而是执行时刻 `t+δ_eff` 的绝对 EE 位姿，再转成相对当前 EE 的 delta。这是 TDR 与普通延迟增强的本质区别；普通增强只把输入换成旧帧，目标仍是 `a_t`，等于教模型「用旧图做旧动作」，不会补偿。这里有一个容易错的实现细节：WLA 的动作是相对 plan-time 当前 EE 的 delta，不能直接拿演示在 `t+δ_eff` 的原始相对动作（那是相对未来 EE 的），必须先重建演示的绝对 EE 轨迹 `T^{demo}_{t+δ_eff+i}`，再算 `Δ_i=(T^{obs})^{-1}T^{demo}_{t+δ_eff+i}`（锚点用模型实际收到的本体位姿 `T^{obs}`；若 API 的 state 比图像新，就用最新 state，图像年龄单独进风险表），否则会引入一个系统性坐标系错位。
2. **真实数据的目标来自演示轨迹**；仿真数据的目标来自特权 oracle/脚本专家在 `t+δ_eff` 的状态下给出的动作。仿真只提供「延迟反事实」，不提供任务语义的最终答案。
3. **零延迟锚定**：25% 的样本 `δ_eff=0`，防止名义性能回退。
4. **延迟分箱均衡**：`w(δ)` 取延迟 bin 的逆频率，裁剪到 `[0.5,2]`；避免 0ms 样本主导。
5. **早停一致性**：`π_K` 停止梯度；`L_con` 让 `k=1..3` 的输出靠近 `k=4`；`L_mono` 鼓励随 `k` 增大误差单调下降。若 `L_mono` 不稳定，设 `λ_m=0`。
6. **仿真权重封顶**：`λ_s≤0.5`；真实验证误差上升 >5% 时减半；仍上升则 `λ_s=0`。
7. **数据划分**：按 session/物体/背景分组，相邻帧不跨 train/val；仿真验证集用未见的纹理/延迟组合。

### 3.3 离线阶段 B：LIS 与风险表

**仿真器**：G1 URDF + Dex1 + 头双目 + 腕部相机模型；MuJoCo 或 IsaacLab；控制 30Hz；延迟队列；N 端口排队模拟。

**闭环仿真循环**：

```text
for episode:
    ξ ~ DR(visual, physics, timing)
    reset(scene(ξ))
    for m = 0,1,...:
        δ_o, δ_a ~ timing(ξ)
        k ~ policy_or_grid
        a_plan = π_θ(o_{t-δ_o}, s_{t-δ_o}, δ_eff, H, k)
        a_cmd = CHUNK_SERVO(a_plan, o_t, goal, K_p(d))
        execute H steps with delay δ_a
        record success / collision / timeout / step progress
```

**风险表上下文**：

| 维度 | 取值 | 数量 |
|---|---|---:|
| 任务族 | peg, hang, stack, zip, unlock, deformable | 6 |
| 相位 | approach, align, contact, transport | 4 |
| δ_eff bin | 0–25, 25–50, 50–100, 100–150, 150–200, >200ms | 6 |
| H | 3, 5, 8, 30 | 4 |
| k | 1, 2, 3, 4 | 4 |
| 计划年龄 bin | fresh (<0.33s), mid, stale (>0.66s) | 3 |

总单元格约 `6×4×6×4×4×3 = 6,912`。每格 30–50 条闭环 episode；稀疏格用分层先验收缩。

**分层 beta-binomial**：

```math
y_{c,i}\sim\mathrm{Bernoulli}(p_c),\qquad
p_c\sim\mathrm{Beta}(\alpha_c,\beta_c),
```

其中 `α_c,β_c` 由父层（任务族×相位）的均值 `μ_parent` 和强度 `κ_parent` 决定：

```math
\alpha_c=\mu_{\mathrm{parent}}\kappa_{\mathrm{parent}},\qquad
\beta_c=(1-\mu_{\mathrm{parent}})\kappa_{\mathrm{parent}}.
```

用经验 Bayes 或轻量 MCMC 拟合；风险上界取后验 `1-α` 分位：

```math
\bar R(c)=Q_{1-\alpha}(p_c\mid\{y_{c,i}\}).
```

若 `n_c<10`，直接用父层上界 `+0.05`。仿真-真机偏移：

```math
\Delta_{\mathrm{shift}}
=
\max\left(0,\ \widehat{R}_{\mathrm{real}}-\bar R_{\mathrm{sim}}\right)
+
\mathrm{UCB}_{95\%},
```

在 5 个单任务真机日志的重叠格上估计。最终：

```math
\bar R_{\mathrm{total}}(c)
=
\min\left(1,\ \bar R(c)+\Delta_{\mathrm{shift}}+\epsilon_{\mathrm{safety}}\right),
```

`ε_safety=0.02`。若 `Δ_shift>0.15`，标记该任务族仿真不可信，降低 `λ_s`，风险表改用真机日志。

**Conformal 备选**：当真机标定样本足够（每格 ≥30）且与部署可交换时，可用 split conformal risk control 给全局风险预算一个分布无关的边际保证；但它不给条件风险保证，因此只作为 sanity check，不替代分层上界。

### 3.4 离线阶段 C：H 选择与增益调度

**H 选择**：H 是提交时固定参数。用单任务通道/干跑测 RTT 分布 `P_δ`；`P(c)` 按 32 任务均匀 + 5 个泛化轴权重，不按榜单分布。对每个候选 H：

```math
J(H)=\mathbb{E}_{c\sim P(c)}[\bar R_{\mathrm{total}}(c;H)]
+\lambda_T\,\mathbb{E}[T_{\mathrm{loop}}(H,k^*)],
```

在 `E[R(H)]≤ε` 和 `K_p H≤η κ^*(d_worst)` 约束下取 `H^*=\arg\min J(H)`。`λ_T` 把毫秒换成风险单位（例如 1ms = 1e-4 风险），需在单任务通道校准；也可改用约束优化：在 `E[R(H)]≤ε` 下最小化 `E[T_loop(H)]`。`J(H)` 用 `T_loop` 作保守上界；实际有缓存复用，平均延迟更低。

**增益调度**：对每个延迟块 `d`：

```math
\kappa^*(d)=2\sin\left(\frac{\pi}{2(2d+1)}\right),\qquad
K_p(d)=\eta\,\frac{\kappa^*(d)}{H}.
```

`η=0.5–0.6`；`K_d` 按同比例缩放；接触相位法向再乘 0.3–0.5（第 12 轮）。增益表按 `d` 索引，在线插值/查表，不学习。

| `δ_eff`（H=5, 30Hz） | `d` | `κ^*(d)` | 安全 `κ=0.6κ^*` | `K_p=κ/H` |
|---|---:|---:|---:|---:|
| 0–166ms | 1 | 1.000 | 0.600 | 0.120 |
| 167–333ms | 2 | 0.618 | 0.371 | 0.074 |
| 334–500ms | 3 | 0.445 | 0.267 | 0.053 |
| 501–666ms | 4 | 0.347 | 0.208 | 0.042 |

注意：`d=0` 只在同一 chunk 内无延迟时出现；远程 API 至少 `d=1`。表中 `K_p` 是抽象增益，实际数值需按 EE 米制误差和动作尺度标定。

### 3.5 在线阶段：AIC governor

伪代码：

```python
class DRTACPolicy:
    def get_action(self, obs):
        t = now()
        delta_o = self.estimate_obs_age(obs, t)
        chi = self.edit_score(obs)
        phase = self.phase_estimator(obs)
        a = t - self.plan_timestamp if self.plan is not None else INF
        c = self.context(phase, chi, delta_o)
        D = (self.H_plan - a) * self.T_c

        # 1) reuse?
        if (self.plan is not None and a <= self.A_reuse[c]
                and chi <= self.theta_chi):
            u = ("reuse", None)
        else:
            feasible = []
            for k in self.K_set:
                delta_i = self.latency_profile(k, self.gpu_queue_len())
                delta_eff = delta_o + delta_i + self.delta_a
                d = ceil(delta_eff / (self.H * self.T_c))
                R = self.risk_table(c, delta_eff, self.H, k, a)
                if (R <= self.epsilon
                        and self.Kp(d) * self.H <= self.eta * self.kappa_star(d)
                        and delta_i + self.delta_a <= D):
                    feasible.append((delta_eff, k))
            if feasible:
                _, k = min(feasible)          # 最小有效延迟
                u = ("refresh", k)
            else:
                # 没有可行刷新：按安全序回退
                u = ("fallback", self.safety_fallback(c, D))

        # 2) issue async refresh
        if u[0] == "refresh":
            self.vla.request(obs, delta_eff, self.H, u[1])
        elif u[0] == "fallback":
            self.handle_fallback(u[1])

        # 3) servo with delay-aware gain
        delta_i = self.latency_profile(active_k, self.gpu_queue_len())
        delta_eff = delta_o + delta_i + self.delta_a
        d = ceil(delta_eff / (self.H * self.T_c))
        Kp = self.Kp(d)
        a_cmd = self.chunk_servo(self.plan, obs, self.goal, Kp, phase)
        return self.adapter.to_api(a_cmd, obs, self.token)
```

**安全回退顺序**：

```text
HOLD（零速、保持夹爪）
  > SERVO_ONLY_CACHED（缓存 plan + 降低增益 + 只做 PBVS 粗对齐）
  > REFRESH(k=K, H 固定)（全步去噪，接受一次延迟）
  > REFRESH(k<K)（快速但风险未证）
```

只有当风险表证明更快选项安全时才选它；否则按上述顺序回退。`HOLD` 不是任务成功，但它保证不因「追求低延迟」而增加碰撞风险。

**滞回**：

- 只在 `δ_eff` 改善 >20ms 或风险余量改善 >10% 时切换 k；
- 计划年龄用双阈值：`a < A_low` 复用，`a > A_high` 强制刷新，中间用场景变化决定；
- RTT 用滑动 90 分位而非均值做安全估计；
- `χ>θ_χ`、`r_grasp` 突变（滑移）、`edit_score` 高 → 强制 `k=K` 刷新 + 降增益。

**多端口共享 GPU**：

- 每个端口独立 `PolicyService`、plan cache、goal、风险统计；模型权重共享。
- 共享 scheduler 维护请求队列；每个请求带 deadline `t+D`；用 EDF 或 least-slack-first。
- 相同 `k` 的请求可批处理；`δ_i(k,q)` 含队列长度 `q`。
- 若 `δ_i(k,q)+δ_a>D`，不排队，直接 reuse/fallback。
- 队列长度超过 `q_max` 时，所有端口暂停发起非紧急刷新，直到降到 `q_low`（滞回）。

### 3.6 与 CHUNK-SERVO 的集成

```text
WLA 30-step plan (async, k-step denoising)
        │
        ▼
AIC: decide refresh(k)/reuse, track plan age
        │
        ▼
CHUNK-SERVO: take H-step slice + servo correction
  - relative goal from demo retrieval
  - contact phase normal/tangential decomposition
  - delay-aware Kp(d)
        │
        ▼
API chunk: H×21D (ee) or H×joint
```

- 30 步 plan 与 H 步 API chunk 解耦；plan 可以跨多个 chunk 复用。
- 伺服在 chunk 边界看到新观测；chunk 内仍然开环（API 限制），但 5 步 = 167ms，已在第 12 轮论证。
- 新算法只改「前馈怎么来、何时刷新、增益多少」，不改「相对目标 + 伺服」本身。
- 如果 AIC 判断必须回退，CHUNK-SERVO 仍然返回合法动作；伺服的 fallback 与第 12 轮一致。

```math
\mathcal{L}

+\lambda_m\mathcal{L}_{\mathrm{mono}}
```

- `L_R`：执行时刻对齐的真实损失，`w(δ)` 加权；
- `L_S`：仿真反事实损失，`λ_s≤0.5`；
- `L_con`：`Σ_k ℓ(π_k, sg(π_K))`；
- `L_mono`：`Σ_k relu(η_k-η_{k+1})`，可选；
- `L_reg`：防遗忘，`λ_r=1e-4`。

早停判据：真实 held-out 的动作误差 + 回放成功率；若 `k=1` 与 `k=4` 的差距 >10%，增加 `λ_c` 或放弃 early-exit（只保留 TDR）。

## 5. 风险表与校准

### 5.1 风险定义

对每个上下文 `c`，`R(c)` 定义为「使用该操作点执行下一个 chunk 时，episode 失败/碰撞/超时/安全违规」的概率。离线用 episode-level 失败标签；在线用代理信号（步骤完成、接触丢失、编辑分数、夹爪滑移）做早期预警。注意：`R(c)` 是 episode 级风险，作为 chunk 级约束的保守代理；在线用 CUSUM/代理信号监测，不把它当成严格的 per-chunk 概率。

### 5.2 采样与分层

- 每个格 30–50 条闭环 episode；稀疏格用父层先验收缩。
- 父层：任务族×相位；再上层：任务族。
- 经验 Bayes 估计 `μ_parent, κ_parent`；留一任务交叉验证。
- 风险表按 `(c)` 哈希/数组索引；在线 O(1)。

### 5.3 仿真-真机偏移

- 在 5 个单任务（PlugInEthernet、HangCup、ZipUp、StackBowls、FoldTowel）上各跑 10 次，记录真实失败与 `\bar R_sim`。
- `Δ_shift` 取重叠格的最大正偏差 + bootstrap 95% 上界。
- 若 `Δ_shift` 大，说明仿真过于乐观；用真机数据替换该任务族的先验，或把 `ε` 降到 0.05。
- 每次真机 A/B 后更新风险表；不把测试集当训练集。

### 5.4 风险表的失效检测

在线监控：

- 实际失败率与预测风险的上偏（CUSUM）；
- 延迟分布漂移（KS 检验）；
- 场景变化/任务类型超出表覆盖（OOD 检测）；
- GPU 队列长度超过校准范围。

任一触发 → 降级：`ε` 减半、`k=K`、`HOLD` 阈值降低；必要时只保留 CHUNK-SERVO。

## 6. 复杂度分析

### 6.1 在线

| 操作 | 复杂度 | 说明 |
|---|---|---|
| 时间估计 | O(1) | 时间戳/RTT/滑动分位 |
| 风险查表 | O(K) = 4 | 常数 |
| 增益查表 | O(1) | 按 d 索引 |
| 伺服 | O(F) | F 为特征数，约 10–100 |
| 调度决策 | O(K log K) | 排序可行 k |
| 单次边界开销 | <1ms CPU | H=5 时边界频率 6Hz |
| 推理 | O(k) 去噪步 | early-exit 省 (K-k)/K |
| 内存 | <2MB | 风险表 + 增益表 + 编码器 |

### 6.2 离线

| 阶段 | 复杂度 | 估算 |
|---|---|---|
| TDR 微调 | 与 action-head 微调同阶 | 20–50k steps，1×24GB GPU |
| LIS 闭环 | O(M·N_sim·T_episode) | M≈6,912，N_sim=30–50，T≈300 步 → 60–100M 步 |
| 风险表拟合 | O(M·N_sim) | 分钟级 |

LIS 是最大成本。若仿真太慢，先做 6 个任务族 × 4 相位 × 4 δ × 3 H × 3 k × 2 age = 1,728 格，每格 30 条，约 15M 步；其余格用插值/父层先验。不要为了表格完整而牺牲真机 A/B 预算。

### 6.3 延迟预算示例（C 级假设）

假设 `f_c=30Hz`，`H=5`，`δ_o=50ms`（已含网络/排队），`δ_a=0`，推理 profile `δ_i(k)=20+30k ms`：

| k | `δ_i` | `δ_eff` | `T_refresh` | `T_chunk` | `T_loop`（最坏） | 相对 k=4 的推理节省 |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 50ms | 100ms | 100ms | 217ms | 267ms | 75% |
| 2 | 80ms | 130ms | 130ms | 217ms | 297ms | 50% |
| 3 | 110ms | 160ms | 160ms | 217ms | 327ms | 25% |
| 4 | 140ms | 190ms | 190ms | 217ms | 357ms | 0% |

这些数字是设计假设，不是实测；G10/G11 必须用真实 profile 替换。实际 profile 应拆成 `δ_i(k)=α+βk`：`α` 是 VLM 编码/图像预处理/网络固定成本，`β` 是每步去噪成本。early-exit 只省 `β(K-k)`；若 `α` 主导（例如 α=200ms、β=20ms），k=1 相对 k=4 只省 60ms，此时低延迟的主杠杆是缓存复用和刷新调度，而不是 early-exit。关键观察：`T_chunk` 固定为 217ms，但 `T_refresh` 随 k 增长；k=4 的 190ms 已经超过一个 chunk 的 166.7ms 执行窗口，意味着全步刷新需要提前一个边界发起，或者下一个边界先用缓存 plan + 伺服。AIC 的价值就在这个「提前多久发起、值不值得 early-exit」的决策上。

## 7. 正确性论证

### 7.1 命题 1：执行时刻对齐降低延迟诱导误差

**假设**：

1. 专家策略 `π^*` 对状态 `L_π`-Lipschitz；
2. 状态速度有界：`||x_t-x_{t-\delta}||≤v_{\max}\delta`；
3. 延迟条件模型在给定 `o_{t-\delta},δ` 下的条件期望误差为 `σ_π(δ)`（Bayes 风险）。

**命题**：

```math
\mathbb{E}\left\|\pi_\theta(o_{t-\delta},\delta)-\pi^*(x_t)\right\|
\le
\sigma_\pi(\delta)+\varepsilon_{\mathrm{approx}}.
```

而零延迟训练的模型在部署时的误差至少包含 `L_\pi v_{\max}\delta` 项：

```math
\mathbb{E}\left\|\pi_0(o_{t-\delta})-\pi^*(x_t)\right\|
\ge
L_\pi v_{\max}\delta-\sigma_0.
```

**证明草图**：三角不等式分解：

```math
\|\pi_\theta(o_{t-\delta},\delta)-\pi^*(x_t)\|
\le
\|\pi_\theta(o_{t-\delta},\delta)-\mathbb{E}[\pi^*(x_t)\mid o_{t-\delta},\delta]\|
+
\|\mathbb{E}[\pi^*(x_t)\mid o_{t-\delta},\delta]-\pi^*(x_t)\|.
```

第一项是估计误差，第二项是条件 Bayes 风险 `σ_π(δ)`。对零延迟模型，`π_0(o_{t-\delta})` 没有把 `δ` 作为条件，无法区分「旧观测对应的旧状态」和「旧观测对应的新状态」；由 Lipschitz 和速度界，至少产生 `L_π v_max δ` 的系统偏差。TDR 把 `δ` 显式作为条件，模型可以学到「旧观测 → 新动作」的条件期望，从而消掉这一项；剩余的是信息缺失导致的条件不确定性。若系统确定性、延迟已知、状态可预测，则 `σ_π(δ)=0`。

**边界**：当 `δ` 超过任务的可预测视界（例如接触后物体运动突变），`σ_π(δ)` 快速上升；此时任何前馈补偿都不可靠，必须靠伺服/回退。风险表负责识别这个边界。

### 7.2 命题 2：延迟依赖的闭环稳定域

考虑第 12 轮的离散误差模型：

```math
e_{m+1}=e_m-\kappa e_{m-d},\qquad \kappa=K_p H,
```

其中 `d` 是延迟块数。特征方程：

```math
z^{d+1}-z^d+\kappa=0.
```

**命题**：稳定域为

```math
0<\kappa<\kappa^*(d)
=
2\sin\left(\frac{\pi}{2(2d+1)}\right).
```

**证明草图**：在稳定边界上，根在单位圆上，`z=e^{j\theta}`。代入：

```math
e^{j(d+1)\theta}-e^{jd\theta}+\kappa=0
\;\Longrightarrow\;
\kappa=e^{jd\theta}(1-e^{j\theta}).
```

模长：

```math
|\kappa|=|1-e^{j\theta}|=2\sin(\theta/2).
```

相位：`1-e^{j\theta}=2\sin(\theta/2)e^{j(\theta/2-\pi/2)}`，所以

```math
d\theta+\theta/2-\pi/2=2\pi m.
```

取最小正解 `m=0`，`θ=π/(2d+1)`，于是 `κ^*=2\sin(π/(2(2d+1)))`。`κ=0` 时根为 `0`（d 重）和 `1`；随 `κ` 增大，根从 `1` 向左移动，首次穿出单位圆发生在 `κ^*`；由连续性，`0<κ<κ^*` 内稳定。

**推论**：

| d | `κ^*` | 安全 `0.6κ^*` |
|---:|---:|---:|
| 0 | 2.000 | 1.200 |
| 1 | 1.000 | 0.600 |
| 2 | 0.618 | 0.371 |
| 3 | 0.445 | 0.267 |
| 4 | 0.347 | 0.208 |

**数值复核（2026-10-31，`numpy.roots` + 二分）**：对 `d=0..5` 二分搜索 `max_i|z_i|=1` 的临界 `κ`，与闭式比较：

| d | 数值 `κ^*` | 闭式 `2sin(π/(2(2d+1)))` | 绝对差 |
|---:|---:|---:|---:|
| 0 | 2.000000000 | 2.000000000 | 2.2e-16 |
| 1 | 1.000000000 | 1.000000000 | 2.0e-12 |
| 2 | 0.618033989 | 0.618033989 | 2.1e-12 |
| 3 | 0.445041868 | 0.445041868 | 2.2e-12 |
| 4 | 0.347296355 | 0.347296355 | 2.2e-12 |
| 5 | 0.284629677 | 0.284629677 | 2.2e-12 |

这只是对线性化模型的数值复核，不替代 G11 的闭环仿真；但它确认了增益表不是拍脑袋的。

多轴情形按逐轴最保守处理：若各轴增益可解耦，逐轴满足 `κ_i≤ηκ^*(d)`；若接触耦合强，用增益矩阵的谱半径替代标量 `κ`，并取更保守的 `η`。

在线 governor 用 `d=ceil(δ_eff/(H T_c))` 查表，强制 `κ≤ηκ^*`。有界预测误差 `ε_m` 下，误差最终有界：

```math
\limsup_{m\to\infty}\|e_m\|
\le
\frac{\|\varepsilon\|}{1-\rho},
```

其中 `ρ` 是稳定裕度对应的收缩率。TDR 降低 `ε`，AIC 降低 `d` 的误判，二者共同扩大稳定域。

### 7.3 命题 3：风险上界的校准语义

**命题（贝叶斯可信上界）**：在分层 beta-binomial 模型和格内可交换假设下，

```math
\Pr\left(R(c)\le \bar R(c)\mid\{y_{c,i}\}\right)\ge 1-\alpha.
```

这是后验可信度，不是频率派保证。加上 `Δ_shift` 后，只有当仿真-真机偏移不超过 `Δ_shift` 时，`\bar R_total` 才是保守上界；这是假设，不是定理。

**频率派备选**：若真机标定数据与部署可交换，split conformal risk control 可给边际风险保证：

```math
\mathbb{E}[R(\hat\lambda)]\le \epsilon+\frac{1}{n+1}.
```

但它不控制条件风险 `R(c)`，所以只作为全局 sanity check。**本报告不声称在非平稳 RTT/新任务下有任何有限样本保证**；在线用保守 `ε`、`Δ_shift`、失效检测和回退来管理这个缺口。

### 7.4 命题 4：回退安全性

定义安全序：

```text
HOLD > SERVO_ONLY_CACHED > REFRESH(k=K) > REFRESH(k<K).
```

**命题（设计不变量）**：在线 governor 只有在风险表证明更快选项满足 `\bar R_total≤ε` 且稳定域约束时，才选择 `REFRESH(k<K)`；否则按安全序回退。若 `HOLD` 被定义为零速、保持夹爪、无新目标，则回退不会增加碰撞风险。

这不是任务成功率定理；它只保证「不会为了低延迟而执行未校准的高速刷新」。任务失败仍然可能发生，但安全风险被隔离。

### 7.5 命题 5：计划年龄的阈值最优性

**假设**：

1. 复用风险 `R(reuse,c,a)` 对 plan 年龄 `a` 单调不降；
2. 刷新风险 `R(refresh(k),c,a)` 与刷新延迟 `T_refresh(k)` 不随 `a` 变化；
3. 可行刷新集合非空，且 `HOLD` 不在正常路径上。

**命题**：存在阈值 `A^*(c)`，使得最优策略为

```math
u^*(a,c)=
\begin{cases}
\text{reuse}, & a\le A^*(c),\\
\text{refresh}(k^*), & a>A^*(c),
\end{cases}
```

其中 `k^*` 是满足风险/稳定/截止约束的最小延迟刷新深度。

**证明草图**：复用相对于刷新的优势是「省下一次 `T_refresh(k)`」；随着 `a` 增大，复用的风险单调上升，而刷新的风险/成本不变，所以一旦刷新优于复用，它在更大的 `a` 上仍然优于复用。用相邻年龄的交换论证可得阈值结构。阈值 `A^*(c)` 可用离线 DP 在年龄 bin 上求得；在线只查表 + 滞回。

**边界**：若风险对年龄非单调（例如目标突然被遮挡后风险反而下降），阈值结构不成立；此时退化为逐点枚举 `|\mathcal{U}|≤5` 个动作，仍然可解，只是没有阈值解释。

### 8.7 任务组合与预算

延迟补偿的收益不是均匀的。按第 12 轮的分档，先测「失败发生在最后 3 厘米、且对延迟敏感」的任务：

| 档 | 代表任务 | 为什么适合/不适合 DR-TAC | 预算 |
|---|---|---|---|
| A：接触/插入/挂/拉链/锁 | PlugInEthernet、HangCup、ZipUp、StackBowls、Unlock、ArrangeTestTubes | 延迟直接变成毫米级前馈偏差；伺服有权修正 | 先测 3–5 个，n=10 |
| B：语义/背景/分类 | FruitSorting、ColorArrangement、OrganizeTools | 主要误差在感知/语义，TDR 边际收益低 | 只做回归，不投入调参 |
| C：变形/长程 | FoldTowel、PackBag | 相对目标和伺服假设弱；TDR 可能无害但无益 | 只做防回归，n=5 |

分配规则沿用第 12 轮：

```text
priority_t = q_t * Δ_t / cost_t
```

`q_t` 是失败发生在最后 3 厘米的比例，`Δ_t` 是配对 A/B 的成功率差，`cost_t` 是标定/仿真/真机成本。每测 3–5 个任务更新一次；不把 320 trials 浪费在未验证的 A/B 上。

- 推理层：固定 4 步 → anytime early-exit + AoI 刷新调度；
- 控制层：固定增益 → 按延迟块数 d 的稳定域增益；
- 评测层：只看成功率 → 成功率 + 计划年龄 + p99 刷新 + 切换率。

**剪枝**：

- 不做第二个 draft/残差模型；
- 不从零训 VLA/World Model；
- 不做完整 sim-to-real 策略训练；
- 不做 30Hz 广域网伺服；
- 不假设在线可变 H；
- 不做力/触觉闭环；
- 不把榜单当难度表；
- 不做 32 任务各一个策略。

## 13. 一句话押注与最大风险

**押注**：用时间域随机化训练同一个 action head 的执行时刻条件，用延迟在环仿真校准风险表，用 AoI-anytime 调度在计划过期前刷新——在不新增模型、不改变 API 契约的前提下，把远程延迟从「系统性偏差」变成「可管理的风险预算」。

**本轮最大风险**：时间域随机化在仿真/回放里学到的延迟补偿，可能迁移不到真实网络抖动和多端口排队造成的非平稳延迟；一旦风险表失准，AIC 会把「更快刷新」变成「更自信地用错计划」。
