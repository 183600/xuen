# 第 2 轮（UniBot 线 · 第 2 轮；本轮灵感：「姿态估计」×「协同控制」）

> **延续而非重基线**：继承 v1「UniBot-SAGE」（U1–U12 / L1–L7 / E601–E618 / IP-01–IP-08）。本轮只解冻 v1 的一个隐含假设——**「最后一环（对齐 / 插入 / 旋转）必须由单臂 VLA 端到端隐式学会」**。新增 U13–U24 / L8–L14 / E619–E636 / IP-09–IP-13，构成 v2「UniBot-COOP」。v1 的合规红线（P5）、剪枝预案与"必保 IP-06/02/03"继续有效。
> **情报更新（检索 2026-11-22）**：官网榜单仍为「即将发布 / Coming Soon」，teaser 状态未变；UnifoLM-WLA-1.0（2026-09-11 发布、09-28 放出 Base 与微调代码）官方定位是 **"One Model Driven, Whole-Body Coordination"**，6B、≈2500h、64 任务（54 桌面 + 10 全身），支持二指与五指手；其 UniBot-V1 数据集任务名可见 HangCup / ArrangePlates / PlugCharger / Unlock / DisconnectEthernet / FoldTowel 等。据此，本轮把「协同控制」明确落在**单机内的双臂 + 躯干全身协同**，而不是多机协同。

## 0. 一句话直觉

VLA 输掉的不是"看不见物体"，而是**没有一把量到毫米级的相对尺子，也没有一个能把两臂 / 躯干当作一个机构来协同的执行器**。姿态估计给前者（带协方差的 6-DoF 相对位姿），协同控制给后者（闭链相对伺服 + 任务优先级全身分配）；二者共享同一个数学红利——**相对量抵消共模误差**。

## 1. 两个灵感词的去歧义与第一性原理

### 1.1 「姿态估计」：不是人体姿态，是 SE(3) 相对位姿 + 协方差

- 三种可能含义：①人体姿态（WBT 数据确有 SMPL）；②机器人自身基座位姿；③物体 / 容器相对位姿。
- 本轮主攻 ③，② 作为使能件，① 只在 v1 IP-05 的全身先验里保留。这个选择由接口决定：评测给的是**头戴双目 + 左右腕相机 + EE 位姿 + 关节状态**，**不给**物体 / 容器位姿、**不给**触觉或力矩。因此"物体在哪、夹住的物体相对目标孔在哪"只能由视觉 + 运动学联合推断。
- 第一性原理：**你无法伺服一个你测不准的量。** VLA 的 latent 不是度量空间；要闭环到亚毫米，必须有一个显式的、带不确定性的相对位姿误差信号。
- 但绝对位姿在未见物体上只有数毫米精度（PoseGAM / AlignPose / FoundationPose / Pos3R 一类方法在 YCB-V 级物体上的公开量级），而插入间隙常常 <1 mm。⇒ 绝对位姿不够；**必须把问题改写成相对位姿 / 直接视觉伺服**。

### 1.2 「协同控制」：不是多机协同，是单机冗余协同

- 三种可能含义：①多机器人一致性；②人机协同；③单机双臂 / 全身协同。评测是"每端口一台 G1"，故取 ③。
- 第一性原理：人形机器人是一个**冗余机构**；官方 32 任务明确含"双手协调"。v1 基本把左臂当摆设、把 `action.pivot` 当可选件。协同控制要求把"手臂 + 另一臂 + 腰 / 腿 pivot"当成一个**可分配的控制资源**。
- 更深一层：**双臂闭链把"绝对定位问题"变成"相对定位问题"**。当两手分别握住物体与容器时，二者的相对位姿是机器人内部量，基座漂移与相机外参共模误差自动抵消。这正是 v1 反复担心的"基座漂移"的解药。

### 1.3 合成：两个灵感词其实是同一件事——相对量抵消共模误差

- 姿态估计的现代做法（多视图 / 双目 / 时序）本质是**用多个视角看同一物体做相对一致性**来压误差；
- 协同控制的闭链本质是**用机器人内部两端的相对约束**来压误差；
- 二者都把 `e_abs = e_base + e_calib + e_percept + e_control` 里的共模项尽量压掉，得到 `e_rel = Δe_calib + Δe_percept + Δe_control`。**严格边界**：双手同树时 `T_{e_L}^{e_R}` 由关节角直接算出，基座项精确相消（产物 L8）；但世界固定的容器不会自动相消，此时要么估基座位姿，要么让第二臂持有容器把它转成相对问题。我们不把"相消"当无条件定理。
- 这就是 v2 的题眼：**Relative-Pose Cooperation（RPC）——用相对位姿把"最后一毫米"变成可控问题，用协同把冗余自由度变成相对精度的来源。**

## 2. 为什么 v1 的路线会卡在最后一环（量化论证）

**误差预算（数字均为文献量级或待测目标，不是已测事实）**：

| 量 | 量级 | 含义 |
|---|---|---|
| 插入间隙（RJ45 / USB / 电池 / 瓶盖 / 插头 / 针头） | ~0.2–2 mm | 任务要求的精度上限 |
| VLA 分块关节动作开环重复性 | ~5–15 mm | 端到端策略的典型量级，待真机核验 |
| episode 内基座漂移 | ~2–10 mm | 绝对控制的主要误差源 |
| 未见物体绝对 6D 位姿 | ~2–10 mm | FoundationPose / PoseGAM / AlignPose 量级 |
| 双目 / 双腕相对位姿（目标） | ≤1 mm、≤1–2° | 本轮要证的可行性 |
| 跟踪误差接触代理（目标） | ~0.1–0.5 mm 等效 | 无力矩时的接触信号 |

**结论**：最后一环的精度需求比 VLA 的开环精度高约一个数量级。这不是"再训大一点"能补的，是**控制结构**问题：缺一个度量相对误差信号，缺一个高频闭环，缺冗余自由度的协同分配。

**与 2026 证据同源**（不是我们的孤立猜想）：
- Coordi-π（arXiv 2610.19753）明确指出 *"precise contact and insertion remain major bottlenecks beyond the choice of bimanual action representation"*——即换更好的双臂动作表示也救不了最后一环。
- BiCoord（arXiv 2604.05831）显示 DP / RDT / π0 / OpenVLA-OFT 在长程紧耦合任务上普遍挣扎。
- VLBiMan（arXiv 2509.21723）的成功要素是"捕捉并重建相对空间关系，强调协调而非绝对运动"。
- PA-BiCoop（arXiv 2606.28192）的辅助臂直接输出"主臂坐标系下的相对位姿"。
- 紧耦合协同双臂（Eng. Mech. Eng. 2026, DOI 10.1007/s11465-026-0873-7）用"协同双臂任务空间 + 固定相对位姿 + 任务优先级关节控制 + CBF 安全滤波"。
⇒ 我们的方向与 2026 SOTA 的诊断一致，但把它从"学一个更好的动作表示"推进到**"显式相对位姿 + 闭链伺服 + 门控切换"**，且严格限定在 UniBot 的观测 / 动作接口内。

## 4. 研究问题（Q6–Q10）

- **Q6（相对位姿可观测性）**：仅用声明观测，能否在未见物体上给出**带校准协方差**的 6-DoF 相对位姿，频率 ≥10 Hz、平移误差 ≤1–2 mm、旋转 ≤1–2°，且 NEES 落在置信区间？
- **Q7（相对伺服的可兑现性）**：在插入 / 旋转类任务上，相对位姿伺服相对 VLA 开环是否能把"最小可插入间隙"降低一个数量级，且**不降低**简单任务成功率？
- **Q8（协同的红利与边界）**：双臂闭链相对控制在哪些任务上严格优于单臂绝对控制？当第二臂不可用时，躯干 pivot + 基座位姿估计能否部分替代？
- **Q9（无扰切换）**：如何在 VLA 与解析伺服之间做不确定性门控的、C1 连续、可随时回退的切换，避免抖动与"两个控制器打架"？
- **Q10（合规）**：解析伺服 + 位姿估计是否仍属"单模型单 API"？（预判：是——不引入第二套学习策略、只用声明观测；但仍需书面确认。）

## 5. 设计原则（P1–P11）

- **P1–P6 继承 v1**：单一计分货币 / 隐状态显式化 / 技能组合 / 推理期吸收偏移 / 合规优先 / 单模型单 API。
- **P7 先测后动**：没有校准协方差的位姿估计不得驱动伺服。
- **P8 相对优先**：能写成相对约束的任务，一律在相对帧控制；绝对帧只用于粗接近。
- **P9 冗余即资源**：第二臂 / pivot 只在"严格降低相对误差"时启用，否则锁死，避免为了炫技牺牲成功率。
- **P10 无扰可逆切换**：任何时刻可退回 VLA，C1 连续、无状态污染、无隐藏模式。
- **P11 不做任务名硬编码**：协同可行性由几何 + 不确定性 + 任务语言 embedding 决定，不用 32 个 `if task == ...`（同时规避 P5 合规红线）。

## 6. MVP 与退化链

**MVP = IP-09（StereoRelPose）+ IP-10（单臂相对伺服）+ IP-11（门控切换）+ v1 IP-06（代理评测）+ 通用 VLA 基线。**
理由：IP-09 是"有没有尺子"，IP-11 是"什么时候敢用"，IP-10 是"敢用之后怎么动"；三者都不需要新硬件、不需要重训大模型，且能被 v1 的代理评测快速证伪。IP-12（双臂 / 躯干协同）是最大差异化，但必须等 P4/E624 探针通过后再投入。

**严格退化链（任一环节不可用 ⇒ 行为回退而非漂移）**：
- Level-0 位姿协方差超阈 / 标定缺失 ⇒ 不伺服，回 VLA；
- Level-1 立体不可用 ⇒ 腕部单目 + 运动学先验，只做粗对齐；
- Level-2 伺服发散 / 饱和 / 跟踪误差异常 ⇒ 立即回 VLA；
- Level-3 第二臂不可用或任务单臂 ⇒ 单臂相对伺服；
- Level-4 整条 LMC 失效 ⇒ 纯基线（保留一份能跑通、可信度合规的最小提交）。

## 7. 预期贡献（可验收）

1. **一个面向 UniBot 观测接口的、带校准协方差的度量相对位姿估计器**，并把误差预算与任务间隙显式挂钩（不是"又一个位姿模型"，而是"能决定该不该介入的位姿模型"）。
2. **一个相对帧闭链伺服控制律 + 任务优先级全身分配**，证明共模基座 / 标定误差相消（L8 / L10），并给出双臂相对单臂的方差缩减条件。
3. **一个不确定性门控 + 无扰切换协议**，把"学习策略 + 解析控制器"安全组合，可作为最后一毫米的通用范式（可迁移到其他榜单）。
4. **一张 32 任务协同可行性地图**：由几何与不确定性推出，而非任务名查表；并量化"哪些任务根本不该用第二臂"。
5. **可审计的最后一毫米日志**：位姿误差、协方差、切换事件、饱和、接触代理、回退次数，全部可导出。

## 8. 本轮最大风险（一句话）

**最大风险**：相对位姿估计在 5 类泛化场景（未见物体、遮挡、背景变化）里恰恰最不可靠，而"自信地估错"会让伺服把机器人带到一个比 VLA 隐式策略更糟的位姿——所以门控必须保守、协方差必须校准、回退必须真正无扰。

## 9. 下一轮迭代计划（深化与修剪，不推倒重来）

- **深化**：协方差校准（NEES / 可靠性图）、接触期旋转（瓶盖 / 解锁）、双臂角色动态分配（主臂 / 辅臂随阶段切换）、基座位姿估计与 pivot 的联合分配。
- **修剪预案**：若 E621 证明"接触时刻的相对位姿误差"与任务成功不相关（|r| < 0.3），则**砍掉 IP-10 / IP-12**，把资源回收到 v1 的抓握线；IP-09 / IP-11 仍作为观测与切换基础设施保留。
- **保留项**：IP-06（评测）、IP-09（感知使能）、IP-11（切换安全）在任何情况下不砍。

## 0. 本轮结论摘要

**一句话路线**：在 v1 三层栈之上插入一个**最后一毫米控制层（Last-Millimeter Control, LMC）**：

```
v1:  接地层(抓握) → 技能层(任务×阶段 MoE) → 适应层(上下文) → 工程层(chunk/延迟/端口)
v2:                          ↑
        ┌─────────────────── LMC ───────────────────┐
        │ StereoRelPose → RelServo → BumplessGate   │
        │      (相对位姿+Σ)   (相对帧伺服)  (门控切换) │
        │                    CoopChain / ContactObs │
        └───────────────────────────────────────────┘
```

其理论支点是 **L8 / L10：相对量抵消共模误差**。这使「姿态估计」与「协同控制」不是两个拼贴的模块，而是同一个误差相消原理的**感知侧**与**执行侧**：

- 感知侧：双目 / 双腕 / 多视图估计**相对位姿**，共模相机误差相消；
- 执行侧：双臂闭链 / 躯干冗余控制**相对位姿**，共模基座与标定误差相消。

**与 v1 的三条差异**：

| 维度 | v1（SAGE） | v2（COOP） |
|---|---|---|
| 最后一环 | 交给 VLA 隐式学习 + 抓握确认 | 显式相对位姿误差 + 解析伺服闭环 |
| 第二臂 / pivot | 基本不用 / 可选 | 闭链协同资源，按几何与不确定性启用 |
| 精度来源 | 更大模型 / 更多数据 | 相对帧共模误差相消 + 高频闭环 |
| 失败模式 | 开环漂移到超时 | 可检测、可回退、可审计 |
| 合规形态 | 单 checkpoint 单 API | 不变；LMC 是 `get_action` 内的解析控制器，不是第二个学习策略 |

**与 2026 SOTA 的关系**：Coordi-π 指出"精确接触与插入仍是双臂动作表示之外的主要瓶颈"；VLBiMan / PA-BiCoop 都把"相对空间关系"作为泛化关键；紧耦合双臂控制已有"协同任务空间 + 任务优先级 + CBF"的成熟骨架。v2 的增量不是重复这些，而是把它们**接进 UniBot 的固定观测 / 动作接口，并加上"该不该接管"的校准门控**。

## 2. 创新点详述

### IP-09 · StereoRelPose：度量相对位姿 + 协方差（P0）

- **动机**：最后一环需要亚毫米级的相对误差信号，而 VLA latent 不是度量空间；评测又不给物体 / 容器位姿与触觉。必须从声明观测里造出这把尺子，并且**知道自己有多不确定**。
- **与现有方案的差异**：现有 VLA 把位姿隐式编码进视觉 token；现有 6D 位姿基础模型（FoundationPose / PoseGAM / AlignPose / Pos3R）追求**绝对**位姿精度，在未见物体上仍是毫米级，且不直接服务"该不该接管"的决策。我们把输出定义为 **`(T̂, Σ)` + 相对量 + 门控可用性**，而不是绝对位姿排行榜。
- **技术可行性：高（分档实现，逐档证伪）**：
  - **A 档（零训练，先跑通）**：现成 6D 位姿 / 分割基础模型（如 FoundationPose 系列、CNOS/DINOv2 系分割）在头双目帧上估物体与容器位姿；用双腕帧估"夹持物体相对 EE"的位姿。先测误差与协方差是否够用。
  - **B 档（多视相对）**：用头双目 + 左右腕四视图，以同一物体 / 容器为锚做**相对**位姿一致性优化（AlignPose 式多视特征对齐 / VGGT 式前馈几何），让共模误差相消。
  - **C 档（腕-腕相对）**：当两手分别持物与容器时，直接估 `T_{wrist_L}^{wrist_R}` 与物体 / 容器在各自腕帧中的位姿，得到机器人内部的相对链。
  - **D 档（直接视觉伺服）**：跳过显式物体位姿，直接在接触区域（孔 / 槽 / 螺纹）上做 IBVS，位姿只用于粗接近。
  - 监督：官方数据无物体真值 ⇒ 用"抓握后物体随臂运动"的刚体一致性 + 多视重投影 + 少量人工标注做自监督 / 伪标签；合成数据补未见物体。
- **所需资源**：数据 = 官方 32 数据集 + 合成 / 增强；算力 = 推理 1 张消费级 GPU 即可（10–20 ms / 帧，降频到 ≥10 Hz）；训练 = 单卡数天（若走 A 档则近零训练）；接口 = 纯 `get_action` 内部，无新增字段。
- **落地步骤**：①P1/P2/P3 探针（标定、真值可得性）；②A 档跑通并在官方数据上测 ADD / 平移 / 旋转误差；③协方差校准（见 L13）；④B/C 档多视相对优化；⑤把输出封装成 `(T̂, Σ, visibility, frame_ids)`；⑥在 v1 代理评测上测"位姿误差 ↔ 失败"相关性（E621）。
- **风险**：①未见物体 / 遮挡 / 反光（最高，见 §9）；②立体未标定；③腕相机被手 / 物体遮挡；④伪标签漂移。缓解：多视冗余 + 协方差门控 + 退化到 D 档。

### IP-10 · RelServo：相对帧伺服（P0）

- **动机**：有了相对误差信号，还需要一个能在 30–100 Hz 内把它压到零、且能利用冗余自由度的控制器。VLA 的 chunk 是开环的，频率与精度都不够。
- **与现有方案的差异**：VLA 用学习到的动作块"隐式"完成对齐；我们用**解析的相对位姿伺服**（比例 + 前馈 + 限幅），并把它嵌进 `get_action` 的输出，仍以 joint chunk 形式返回，对评测端完全透明。
- **控制律（单臂起步）**：设 `T_o^r` 为物体到容器的相对位姿，目标 `T_o^{r,*}`，误差 `E = (T_o^{r,*})^{-1} T_o^r ∈ SE(3)`，`ξ = log(E) ∈ se(3)`；期望 EE twist `v_d = -K ξ`（K 为 6×6 正定增益，按轴解耦）；经相对雅可比 `J` 映射为关节速度 `q̇ = J^+ v_d + (I - J^+J) q̇_posture`。
- **任务优先级 QP**（L12）：优先级 0 = 关节 / 速度 / 碰撞（CBF）硬约束；优先级 1 = 相对位姿误差；优先级 2 = 姿态 / 可操作度；优先级 3 = 关节居中。用层次 QP 或零空间投影实现。
- **相位与所有权**：只在 `z_phase ∈ {align, insert, rotate}` 且门控通过时接管；`reach / transport` 仍由 VLA 主导，避免"两个控制器打架"。
- **所需资源**：算力 = <1–2 ms / 步（QP 小规模）；数据 = 无（解析）；接口 = joint chunk，与 v1 的 `control_space=joint` 一致。
- **落地步骤**：①在仿真 / 回放里验证 SE(3) 误差与雅可比符号；②单臂插入（PlugCharger / DisconnectEthernet 类）A/B；③加限幅、抗饱和、发散检测；④与 v1 IP-03 的 chunk 缝合 / 延迟整形对接；⑤双臂版本见 IP-12。
- **风险**：①奇异位形 / 关节限位导致饱和；②接触后纯位置伺服会顶死（需 IP-13 顺应）；③与 VLA 的所有权边界不清导致抖动（需 IP-11）；④相对位姿估计延迟造成相位滞后（用 Smith 预测 / 前馈补偿）。

### IP-11 · BumplessGate：不确定性门控 + 无扰切换（P0）

- **动机**：解析伺服在"估得准、间隙够、相位对"时很强，在"估错"时比 VLA 更危险。必须有一个**可证明保守**的接管判据，以及一个**不会制造尖峰**的切换。
- **门控（U15）**：`G=1` 当且仅当：
  1. `z_phase ∈ {align, insert, rotate}`；
  2. 可见性 / 分割置信度 `> v_min`；
  3. `λ_max(Σ) < σ_max`；
  4. **误差预算**：`3·sqrt(tr(Σ_trans)) < c_task / κ`（`c_task` 为估计间隙，`κ` 为安全系数，建议 2–3）；
  5. 协同可行性（若用 IP-12）通过。
- **无扰切换（U19）**：`a_t = (1-α_t) a_t^VLA + α_t a_t^servo`，`α_t` 用 smoothstep 在 `N_blend`（建议 3–5）步内从 0→1；要求伺服首动作在位置与速度上匹配 VLA 末动作（用 v1 IP-03 的 `last_action` 与一阶外推）；退出用**迟滞**（`τ_in < τ_out`）+ 最小驻留时间，避免抖动。
- **随时回退（U24）**：若相对误差连续 `k` 步不降、或关节速度饱和、或位姿协方差突增，立即 `α→0` 并回 VLA；回退不重置 VLA 的 episode 状态。
- **所需资源**：算力 = O(1)；数据 = 无；接口 = 无。
- **落地步骤**：①状态机（VLA-only / blend-in / servo / blend-out / aborted）；②混合与匹配；③迟滞与驻留；④抖动 / jerk 指标；⑤故障注入（人为给错位姿）验证回退。
- **风险**：①门控过保守 ⇒ 永远不接管（收益为 0）；②门控过激进 ⇒ 误伤；③切换延迟 ⇒ 错过接触窗口；④状态污染。缓解：E628 专门测假阳性 / 召回，阈值由数据定。

### IP-12 · CoopChain：双臂 / 躯干闭链协同（P1）

- **动机**：官方 32 任务含"双手协调"；人形机器人是冗余机构；v1 基本没用第二臂与 pivot。双臂闭链能把绝对定位变成相对定位（L8/L10），这是"协同控制"真正的红利。
- **与现有方案的差异**：VLBiMan / PA-BiCoop 学"相对空间关系"或"主辅臂相对位姿"，但仍以学习策略为主；我们把它做成**解析闭链约束 + 任务优先级全身控制**，作为 VLA 的最后一毫米接管层，且**只在几何可行时启用**。
- **数学骨架**：设两手 EE 位姿 `T^{e_L}`, `T^{e_R}`，闭链约束 `C(q) = log((T^{e_R})^{-1} T^{e_L} (T^{e_L,e_R,*})^{-1}) = 0`；相对雅可比 `J_rel = J_R - Ad_{T^{e_R}}{}_{e_L} J_L`（按具体坐标约定展开）；把 `J_rel` 放进 IP-10 的 QP 作为优先级 1，躯干 `pivot` 作为额外自由度参与零空间分配。**关键**：两手同树时 `T_{e_L}^{e_R}` 由关节角直接算出，基座漂移精确相消（L8）；若容器固定在世界，则不能相消，需估基座位姿或让第二臂持容器。
- **协同可行性（U21 / L14）**：第二臂必须能到达目标 / 容器的抓 / 扶位，且 `rank(J_rel)=6` 覆盖所需方向；否则锁死第二臂，退回单臂。
- **协同任务分类（决定用哪一档控制）**：

  | 类 | 判据 | 相对控制形态 | 基座漂移 |
  |---|---|---|---|
  | **A 双臂相对** | 两手分别持物与容器（或同时持同一物） | 闭链 `J_rel` 精确伺服 | 精确相消（L8） |
  | **B 世界锚定** | 容器固定在桌面，单臂插入 | EE–容器相对位姿 + 基座位姿估计 | 需估 `B`，不完全相消 |
  | **C 单臂自由** | 无容器 / 纯抓放 | 单臂相对伺服（物体–EE） | 需估 `B` |
  | **D 不可协同** | 第二臂不可达 / 会破坏其他子任务 | 锁死第二臂，只用 C 档 | — |

  分类由几何与 `rank(J_rel)` 在线判定，**不查任务名**（P11）；官方 32 任务的具体归属由 P4/E624 探针确认。
- **所需资源**：算力 = QP 稍大（仍 <3 ms）；数据 = 无；接口 = 用现成的 `left/right_arm` 与 `pivot`。
- **落地步骤**：①P4 探针：确认哪些任务允许 / 受益于第二臂；②在仿真 / 回放验证闭链与相对雅可比；③单臂 vs 双臂 A/B；④角色动态分配（主臂 / 辅臂随阶段切换）；⑤失败时自动释放第二臂。
- **风险**：①第二臂占用导致其他子任务失败（如需要同时抓别的物体）；②碰撞 / 自碰撞；③某些任务明确单臂；④`pivot` 语义 / 跟踪未知（继承 v1 P5）。缓解：可行性判据 + 自动锁死 + 只在明确收益时启用。

### IP-13 · ContactObserver：无力矩接触代理 + 旋转对位（P1）

- **动机**：接口没有力矩 / 触觉，但插入 / 旋转是接触丰富任务。纯位置控制在接触后会顶死或滑脱。需要"无传感器的力 / 接触"估计。
- **与现有方案的差异**：v1 的抓握确认用"随臂运动"间接判断；这里把它扩展成**扰动观测器**：用指令与实测的差异估外扰。
- **方法**：若底层是位置 / 速度控制，`f̂_ext ≈ K_p (q_cmd - q_obs) + K_d (q̇_cmd - q̇_obs)`（或动量观测器 `r = K_o (p - ∫(τ + C^T q̇ - g + r)dt)`）；把 `f̂_ext` 的突变作为接触事件，把持续偏置作为接触力代理。旋转对位：用视觉检测螺纹 / 键槽相位，叠加小幅螺旋搜索 + 顺应（admittance）控制。
- **所需资源**：算力 = <1 ms；数据 = 无（参数需标定）；接口 = 只用关节状态。
- **落地步骤**：①P6 探针（有无力矩）；②无力矩时标定 `K_p/K_d` 代理；③接触事件检测延迟与误报；④旋转任务（Unlock / 瓶盖）专项 A/B。
- **风险**：①摩擦 / 重力 / 模型误差被误判为接触；②代理力不准导致过度顺应或顶死；③旋转搜索破坏场景。缓解：只在低速 / 小步长时用，设力 / 位移上限。

## 3. 符号与定义（U13–U24）

| 符号 | 含义 |
|---|---|
| `T_a^b ∈ SE(3)` | 把 b 系坐标映到 a 系的齐次变换（b 相对 a 的位姿） |
| `(T̂, Σ)` | 位姿估计与 6×6 协方差（在 `T̂` 的切空间，`T = T̂ exp(ξ^)`，`ξ~N(0,Σ)`） |
| `ξ = log(E) ∈ se(3)` | SE(3) 误差的对数映射（6 维 twist） |
| `c_task` | 任务估计间隙（最小可插入余量） |
| `G(o_t) ∈ {0,1}` | 门控：是否允许解析伺服接管 |
| `J_rel` | 双臂相对雅可比 |
| `f̂_ext` | 无力矩时的外扰 / 接触代理 |
| `α_t ∈ [0,1]` | 切换混合系数（C1） |
| `Π` | v1 的非抓取原语库（继承） |

**定义 U13（相对位姿）** `T_a^b` 为 b 相对 a 的位姿；`T_o^r = T_w^r (T_w^o)^{-1}` 为物体到容器的相对位姿。
**定义 U14（带协方差位姿估计）** 估计器输出 `(T̂, Σ)`，并约定 `T = T̂ exp(ξ^)`、`ξ ~ N(0, Σ)`；`Σ` 在体坐标系表达。
**定义 U15（门控）** `G(o_t)=1 ⇔ z_phase∈{align,insert,rotate} ∧ vis>v_min ∧ λ_max(Σ)<σ_max ∧ 3√tr(Σ_trans) < c_task/κ ∧ (coop_feasible ∨ ¬use_coop)`。
**定义 U16（协同闭链）** 约束 `C(q)=log((T^{e_R})^{-1}T^{e_L}(T^{e_L,e_R,*})^{-1})=0`，即两手保持目标相对位姿。
**定义 U17（任务优先级控制）** 层次 QP：`min ‖J_rel q̇ − v_d‖²` s.t. 安全约束；低优先级目标投影到高优先级零空间。
**定义 U18（双臂相对量的基座无关性）** 同一运动学树上两末端 `T_{e_L}^{e_R} = (T_b^{e_L})^{-1} T_b^{e_R}` 仅由关节角 `q` 决定，与浮动基座位姿 `B` 无关；但世界固定的容器 `T_e^r = (T_b^e)^{-1} B^{-1} T_w^r` 仍含 `B`。
**定义 U19（无扰切换）** `a_t = (1-α_t)a_t^VLA + α_t a_t^servo`，`α` 为 smoothstep 且满足位置 / 速度匹配；进入 / 退出用迟滞 + 最小驻留。
**定义 U20（误差预算）** 允许伺服的条件 `3σ ≤ c_task/κ`；`σ = √tr(Σ_trans)`。
**定义 U21（协同可行性）** `coop_feasible=1` 当第二臂可达抓 / 扶位且 `rank(J_rel)=6` 覆盖所需方向。
**定义 U22（接触顺应）** 在接触帧内 `ẋ = ẋ_cmd + A(f̂_ext − f_ref)`，`A` 为 admittance 增益；`f̂_ext` 超阈时减速 / 停。
**定义 U23（协方差校准）** `NEES = ξ^T Σ^{-1} ξ`；若估计器一致，6-DoF 下 `E[NEES]≈6`；偏大则膨胀 `Σ`。
**定义 U24（恢复）** 连续 `k` 步误差不降 / 饱和 / 协方差突增 ⇒ `α→0`、回 VLA、不重置 VLA 状态。

class StereoRelPose:
    def estimate(self, obs):
        # 头双目 + 双腕；帧间以同一物体/容器为锚

                 obs["observation.images.cam_right_high"][-1],

        # 多视相对一致性：以物体为锚，压共模误差

# ===== IP-11：门控 + 无扰切换 =====
class BumplessGate:
    def __init__(self, sigma_max=0.004, kappa=2.5, n_blend=4, tau_in=0.003, tau_out=0.006):
        self.sigma_max, self.kappa, self.n_blend = sigma_max, kappa, n_blend
        self.tau_in, self.tau_out = tau_in, tau_out
        self.state, self.dwell, self.alpha = "vla", 0, 0.0

    def step(self, phase, T_o_r, Sigma, c_task, vis):
        sigma = (trace(Sigma[:3, :3]) + trace(Sigma[3:, 3:])) ** 0.5
        ok = (phase in ("align", "insert", "rotate") and vis > 0.5
              and max_eig(Sigma) < self.sigma_max
              and 3 * sigma < c_task / self.kappa)
        # 迟滞：进入用 ok，退出用更宽松的 ok_out
        if self.state == "vla" and ok and self.dwell >= 1:
            self.state, self.dwell = "blend_in", 0
        elif self.state in ("servo", "blend_in") and not ok:
            self.state, self.dwell = "blend_out", 0
        # alpha 用 smoothstep，保证 C1
        if self.state == "blend_in":
            self.alpha = min(1.0, self.alpha + 1 / self.n_blend)
            if self.alpha >= 1.0: self.state = "servo"
        elif self.state == "blend_out":
            self.alpha = max(0.0, self.alpha - 1 / self.n_blend)
            if self.alpha <= 0.0: self.state = "vla"
        self.dwell += 1
        return self.alpha, self.state

# ===== IP-10 + IP-12：相对帧伺服 + 任务优先级 QP =====
class RelServo:
    def act(self, q, T_o_r, T_target, Sigma, pivot, use_coop, other_arm):
        E = inv(T_target) @ T_o_r
        xi = se3_log(E)                              # 6 维误差
        v_d = -self.K @ xi                           # 期望相对 twist
        J = self.rel_jacobian(q, use_coop)           # 单臂或双臂 J_rel
        # 层次 QP：安全 > 相对位姿 > 姿态 > 关节居中
        qdot = self.qp_solve(J, v_d, q, pivot,
                             joint_lim=self.joint_lim,
                             vel_lim=self.vel_lim,
                             cbf=self.collision_cbf(q))
        return qdot

# ===== 主策略：把 LMC 嵌进 v1 的 get_action =====
class UniBotCOOPPolicy:
    def get_action(self, obs, port):
        s = self.sessions[port]
        phase = self.fc.predict(obs)                 # v1 U3
        ztask = self.task_router(obs["observation.language"])
        c = self.ca.encode(obs)                      # v1 U9
        T_o_r, Sigma, vis = self.pose.estimate(obs)  # IP-09
        c_task = self.clearance.estimate(obs, ztask) # 几何 / 任务先验
        alpha, state = self.gate.step(phase, T_o_r, Sigma, c_task, vis)

        a_vla = self.model.act(obs, ztask, phase, c, self.chunk_len(phase))
        if alpha > 0:
            use_coop = self.feasible(obs, T_o_r, Sigma)   # IP-12 / U21
            a_srv = self.servo.act(obs["observation.state"], T_o_r,
                                   self.target(ztask), Sigma,
                                   obs["observation.state.lower_body"],
                                   use_coop, s.other_arm)
            a_srv = self.match_velocity(a_srv, s.last_action)  # 无扰
            a = (1 - alpha) * a_vla + alpha * a_srv
        else:
            a = a_vla
        a = self.stitch_and_guard(a, s.last_action)   # v1 IP-03 / U12
        s.last_action = a[-1]
        return self.pack(a)

class ContactObserver:
    def update(self, q_cmd, q_obs, qd_cmd, qd_obs):
        # 位置/速度级代理；参数 Kp/Kd 需标定（P6）
        f_proxy = self.Kp * (q_cmd - q_obs) + self.Kd * (qd_cmd - qd_obs)

        return f_proxy, contact

    def admittance(self, xdot_cmd, f_proxy):

        return xdot_cmd + self.A @ (f_proxy - self.f_ref)

## 5. 推导（引理 L8–L14）

**引理 L8（双臂相对量的基座无关性；以及它的边界）** 设两末端在同一运动学树上，浮动基座位姿 `B = T_w^b`。正运动学给出 `T_b^{e_L}(q)`、`T_b^{e_R}(q)`，于是 `T_{e_L}^{e_R} = (T_b^{e_L})^{-1} T_b^{e_R}` 仅依赖 `q`，与 `B` **精确**无关（不是近似）。⇒ 双臂闭链相对控制对基座漂移不变。**边界（必须写明）**：若目标 / 容器固定在世界上，则 `T_e^r = (T_b^e)^{-1} B^{-1} T_w^r` 显含 `B`，基座漂移**不会**相消；这类世界锚定任务（Class B）必须额外估 `B`（基座位姿估计），或让第二臂持有容器把它转化为 Class A。E626 专门验证这条边界，而不是把它当作无条件定理。∎
**引理 L9（误差预算可行性）** 若真实相对位姿以 ≥0.997 概率落在 `3σ` 椭球内，且椭球最大轴 `≤ c_task`，则存在一条不碰撞的伺服路径使误差单调下降（在凸间隙近似下）；反之若 `3σ > c_task`，则存在不可忽略概率把误差方向判反，导致顶死 / 卡死。⇒ 门控条件 U20 是"安全接管"的必要条件（非充分）。∎

**引理 L10（相对控制的方差缩减条件）** 世界锚定单臂的误差 `e_abs = e_base + e_calib + e_percept + e_control`；由 L8，双臂同树相对量消去 `e_base`，`e_rel = Δe_calib + Δe_percept + Δe_control`。若基座漂移方差 `σ_base²` 大于差分感知方差 `2σ_percept²`，则 `Var(e_rel) < Var(e_abs)`，相对控制严格更优；反之若差分感知误差占主导，相对未必更好，此时必须靠多视 / 腕-腕估计压差分项。⇒ 双臂红利来自"基座漂移占主导"这一可检验条件（E626），不是无条件成立。∎

**引理 L11（无扰切换稳定性）** 若 `α(t)` 为 C1（smoothstep）、两控制器输出有界、门控有迟滞（`τ_in<τ_out`）且最小驻留 `d_min`，则混合动作有界、jerk 有界（由 `α̇` 与两控制器差的上界决定），且不存在零周期抖振。∎

**引理 L12（任务优先级安全）** 层次 QP 中，低优先级目标的解位于高优先级约束的零空间内，故相对位姿目标不会破坏关节 / 速度 / 碰撞（CBF）硬约束。∎

**引理 L13（NEES 校准）** 若 `ξ~N(0,Σ)` 且估计器一致，则 `NEES~χ²_6`、均值 6。若实测均值显著 >6（过度自信），按比例膨胀 `Σ` 直到均值落入置信区间；膨胀只会让门控更保守，不会增加误伤。∎

**引理 L14（协同可行性）** 任务可协同当且仅当第二臂可达抓 / 扶位且 `rank(J_rel)` 在所需任务方向为满秩；否则闭链无法独立控制所需相对自由度，应退回单臂。∎
