# 第 43 轮（新循环第 3 轮） · CertOps × 可恢复性证书（FRC）：把证书飞轮从「实验室闭环」推进到「可灰度、可回滚、可恢复」的产品化运维（四层两平面 v8）

> 承接第 42 轮 v19（SCV × CKB × ECR）。第 42 轮自陈最大风险是「仿真偏差累积 + 检索幻觉」。本轮灵感词「应用落地」「失败恢复」击中两个更深的命门：飞轮再精密，若不能以可控爆炸半径部署到异构车队、不能把机器人从故障中救回来，它就仍是实验室玩具；而 SafeStop 不是恢复，只是把失败推迟给运维。本轮把「证书」当作需要 SRE 化运营的软件制品，把「恢复」证书化为第一类公民：新增 CertOps 控制平面、恢复引擎与 FRC，形成 Field→Sim→KB→Edge→Canary→Field 的运维闭环。

## 0. 直觉与动机

**灵感 1（应用落地 → 证书是运维对象，不是论文附件）**：第 42 轮证明了飞轮能「进化」，但没回答「怎么交付」。真实落地的摩擦不在算法，而在四件事：异构车队（不同传感器/执行器/算力）、部分可观测（现场遥测丢包、时钟漂移）、人机共驾（操作员接管与复位）、集成与合规（ROS 2、DDS、功能安全审计）。直觉是把证书当软件发布：**签名制品 + 影子模式 + 灰度 + 一键回滚 + 审计留痕**。证书不是「证明一次就完」的静态文件，而是「部署—观测—回滚」的持续运维对象；落地不是把阈值放松，而是让失败更早暴露、爆炸半径更小、回滚更快。

**灵感 2（失败恢复 → SafeStop 是逃避，不是交付）**：前 42 轮的降级链终点是 Degraded/SafeStop。对产品而言，停在 SafeStop 就是可用性事故；对安全而言，只证「不撞」不证「能回来」是半边证书。恢复的直觉是给恢复本身发证书：**FRC（Failure Recovery Certificate）**——对每个可降级状态，证明「存在一条恢复策略，在 T_r 内以 ≥1−δ 概率回到 Nominal，且全程不越过弱安全界 S_weak」。这把「安全但瘫着」变成「安全且能回来」，补上了只有 safety、没有 liveness 的结构性缺口。

**灵感 3（两者耦合 → 恢复阶梯 × 失败预算 × 灰度）**：恢复不是二元动作，而是阶梯：R0 收紧裕度继续、R1 降速降力、R2 切换模态/重定位、R3 停机重启、R4 人工接管；每级有**能力损失 c_r、成功概率 p_r、恢复时间 T_r、切换风险 ρ_r**。选级是带约束的序贯决策。部署侧用**失败预算账本**（risk ledger）而非「花钱买安全」：按危险类别设硬上限、不可跨类挪用，超支即冻结车队发布；灰度按爆炸半径 BR = p·N_fleet·E[C_fail] 逐级放量。恢复、近失、漂移三种遥测共同驱动 SCV 重放与证书重算，形成可运营的闭环。

**耦合升级**：第 42 轮是 Sim→RAG→Edge→Sim 的「学习飞轮」；本轮加上 **Field→Canary→LKG→Field 的「运维飞轮」**。学习飞轮负责「更准」，运维飞轮负责「更稳地交付」；两者通过证书制品仓库、FRC 与失败预算账本耦合。

## 1. 形式化定义（增量：定义 38–45）

**定义 38（证书 SLO 向量）**：证书版本 v 的 SLO_v = (A_v, S_v, R_v, E_v)，分别表示 Nominal 时间占比（可用性）、每机器人小时安全违例率、恢复时间分位数（p95/p99）、人类介入率。发布验收 = 在置信水平 1−δ 下同时满足 (A≥A_min, S≤S_max, R≤R_max, E≤E_max)。把「安全」从布尔值变成可观测、可回归的多维 SLO。

**定义 39（失败恢复自动机 FRA）**：FRA = CAR ⊗ A_fault ⊗ A_rec。A_fault 由故障检测器 Δ_fault 驱动，状态含 Nominal、Degraded_i、SafeStop、Recovery_r、HumanHandoff；恢复边 e_r 的守卫为 FRC(s)，即「当前状态存在有效恢复证书」才允许转移。恢复边带标签 (r, c_r, p_r, T_r)。**非恢复边不可由恢复引擎触发**，保证恢复只能选择已被证书化的动作。

**定义 40（可恢复性证书 FRC）**：对降级状态 s ∈ D，FRC_{δ,T}(s) = (π_r, S_weak, T, δ, cost) 满足：
(1) 生存不变式：在 π_r 下 ∀t≤T, x_t ∈ S_weak（弱安全集，允许能力下降但不允许不可逆伤害）；
(2) 可达性/活性：Pr^{π_r}[◇_{≤T}(x ∈ S_safe)] ≥ 1−δ；
(3) 动作可证：恢复期所有动作 a_t ∈ A_certified(s)，不可调用未认证的「赌一把」动作。
可恢复域 D_cert = {s : FRC(s) 成立}；不可恢复集 U = D \ D_cert 必须在设计期用硬件/机械联锁排除，而不是运行时「希望它不发生」。

**定义 41（恢复阶梯与约束选择）**：L = {R0,…,R4}，每级 r ↦ (c_r, p_r, T_r, ρ_r)。恢复策略 π_r 是阶梯上的一个序列；选择问题为
max_π Pr_return(π) s.t. Σ c_r ≤ B_cap, Σ T_r ≤ T_budget, Pr_return(π) ≥ 1−δ, ρ(π) ≤ ρ_max。
p_r、T_r 不取点估计，而取**单边置信下界/上界**：p_r^LB = Clopper–Pearson(k_r, n_r, δ_p)，T_r^UB = 保形分位数（conformal quantile, 1−δ_T）。若各级共享同一故障源，禁止用独立乘积 1−∏(1−p_i)，改用 Fréchet–Hoeffding 上下界保守合成。

**定义 42（证书灰度发布与爆炸半径）**：发布计划 p_1<…<p_m（如 1%→5%→20%→100%），每级用 SPRT/贝叶斯停止规则在 (H0: 不回归, H1: 回归) 间决策。爆炸半径 BR(p)=p·N_fleet·E[C_fail]；仅当 BR(p) ≤ B_remaining 且该级 SLO 置信验收通过才晋级。回滚目标为 last-known-good (LKG)；证书/KB/模型用**两阶段提交**更新，禁止「半新半旧」的混合状态。

**定义 43（失败预算账本）**：B_total 按危险类别（碰撞/失稳/越界/任务失败）分配为不可跨类挪用的硬上限 B_h。账本记录每次恢复进入弱安全集、每次近失、每次灰度回归的「风险消耗」；一旦某类 B_h 耗尽，冻结对应类别的发布并要求根因分析。**失败预算不是安全许可证，而是审计与分配工具；它不可为负，也不可用于「抵消」已发生的违例。**

**定义 44（近失事件与恢复演练）**：近失事件 = margin ∈ (θ_alert, θ_trip) 或「恢复被触发但成功」的事件。近失集 NM 经 IP-54 归因后入 CKB，作为领先指标；影子模式下定期注入故障做**恢复演练**，用演练通过率与真实恢复成功率之差衡量 FRC 的泛化缺口。

**定义 45（部署 TCO v3 与 MTTR 模型）**：COT_v3 = C_sim/N + C_edge·T + C_ops + C_down·MTTR·N_inc + C_human·N_verify。C_ops 含灰度、监控、值班、审计；MTTR 由恢复阶梯的期望时间与检测时延组成。优化目标从二维 (COT, 安全) 升级为三维 (COT, SLO 违例, 恢复成功率)，显式给出 Pareto 前沿。

## 2. 产出设计（新增 IP-57/58/59 + 升级既有 IP）

### 2.1 IP-57 CERTOPS（证书运维控制平面）
1. **证书制品仓库**：每个版本打包 {证书哈希, KB 快照, 模型哈希, Sim 配置哈希, 硬件 profile, 依赖版本}，签名 + 溯源（git commit / SBOM）。
2. **灰度控制器**：shadow（只推理不执行）→ canary（小比例执行）→ staged → fleet；SPRT 决策、爆炸半径门禁、LKG 回滚、两阶段提交。
3. **异构车队配置**：按传感器/执行器/算力 profile 自动选择证书变体；能力注册表记录每台机器人的「已证能力」。
4. **审计包**：把 SLO 轨迹、近失、恢复事件、回滚记录映射到功能安全/认证条款，支持现场审计与事故复盘。

### 2.2 IP-58 RECOVERY-ENGINE（恢复引擎与 FRC 验证器）
1. **故障检测与隔离**：残差（状态/语义/时序）触发 FDI，输出故障类别与置信；检测时延计入 MTTR。
2. **恢复阶梯策略库**：R0–R4 的参数化策略；约束选择器按定义 41 求解；带迟滞与最大重试次数，防「恢复抖动」。
3. **检查点/重构**：对感知地图、规划状态、任务栈做检查点；恢复时选择「重启局部」而非「全局重启」。
4. **FRC 校准与重认证握手**：SCV 故障注入 + Clopper–Pearson/保形分位数给出单边保证；恢复后必须向 CAR 重新申请证书，未通过则继续阶梯或 HumanHandoff。
5. **硬件安全内核**：E-stop、力矩/速度限幅、独立看门狗放在 MCU/安全 PLC，恢复软件不可越过。

### 2.3 IP-59 FIELD-OBSERVABILITY（现场可观测性与近失挖掘）
1. **事件溯源遥测**：统一事件 schema（状态、裕度、故障、恢复、模式），PTP 对齐时间戳，支持离线重放。
2. **近失挖掘与归因**：复用 IP-54 的归因器，区分「差点失败」与「恢复成功」，输出领先指标。
3. **漂移/恢复双仪表盘**：S_t（第 42 轮）与恢复成功率、MTTR、阶梯分布、抖动率联合展示。
4. **隐私与带宽约束**：上行只传特征/摘要，不传原始视频；边缘侧做聚合与差分隐私。

## 4. 实验设计（E87–E94 硬门槛，承接 E79–E86）

| 实验 | 指标 | 门槛 |
|---|---|---|
| E87 FRC 覆盖与假认证率 | 可恢复域覆盖率；宣称可恢复但实际失败率（假认证） | 覆盖 ≥90%；假认证 ≤0.1% |
| E88 恢复阶梯有效性 | 注入故障后 T_budget 内回到 Nominal 比例；MTTR p95；能力损失 | ≥95%（真不可恢复除外）；<30s；<30% |
| E89 灰度回滚与爆炸半径 | 坏证书检出率；回滚时间；爆炸半径；灰度期不安全事件 | 检出 ≥99%/50 次部署；<5min；≤1% 车队；0 起 |
| E90 异构车队适配 | 10 种硬件/5 种退化下 E79+E87 通过率 | 配置 ≥95% 通过；失效可解释 |
| E91 故障恢复覆盖 | FMEA 故障模式映射到恢复路径的比例；检测召回 | 100% 映射；检测 ≥99% |
| E92 OTA 热切换 | 两阶段提交一致性；停机时间；坏包回滚 | 0 不安全；<2s；坏包 100% 回滚 |
| E93 失败预算/近失 | 近失对后续故障的预测 P/R；账本对账一致性 | 召回 ≥80%，精确 ≥70%；对账 100% |
| E94 现场长跑 | ≥20 台 × 2000 机器人小时：不安全事件、可用性、MTTR、人工介入 | 0 起；≥95%；<60s；<1 次/100h |

回退：E87 假认证超限 → 缩小 D_cert 并把边界状态划入 U，同时提高 T_r 保守度；E88 恢复失败 → 默认降到 R3+R4，禁止自动重入；E89 灰度异常 → 冻结发布、回滚 LKG、人工审计；E92 热切换不安全 → 退回「停机升级 + 人工确认」；E93 近失无预测力 → 仅作审计不作触发；E94 现场不达标 → 缩减部署规模，回到 D2 影子模式。

## 5. 本轮最大风险（一句话）

**一句话**：恢复引擎把「停」换成「救」，但恢复本身是样本更稀少的新风险源——若 FRC 在训练分布外高估成功率、或灰度与遥测不完整导致过早重认证与恢复抖动，机器人会以「正在恢复」的名义进入比 SafeStop 更危险的状态；因此 E87（假认证率）与 E89（灰度回滚/爆炸半径）必须设为红线，任一失败即冻结发布并回退 LKG。

## 2. 关键算法（伪代码）

### IP-58：FRC 校准（统计单边保证 + Sim-to-Real 传递）
```
def calibrate_frc(region, sim, policy_lib, n=2000, dp=0.01, dT=0.01,
                  T_budget=30.0, p_req=0.95):
    # 并联界：成功概率下界置信 1-dp，恢复时间上界置信 1-dT
    frc = {}
    for s0 in sample(region):
        recs = []
        for _ in range(n):
            fault = sim.fault_model.sample()
            traj = sim.rollout(s0, policy=policy_lib.select(s0, fault), fault=fault)
            ok = traj.stays_in(S_weak) and traj.reaches(S_safe, within=T_budget)
            recs.append((ok, traj.t_recover))
        k = sum(ok for ok, _ in recs)
        if k == 0:
            frc[s0] = UNKNOWN          # 运行时按不可恢复处理（保守）
            continue
        p_lb = clopper_pearson_lower(k, n, dp)
        T_ub = conformal_quantile([t for ok, t in recs if ok], level=1-dT)
        # Sim-to-Real：第 42 轮 W1 迁移界 + 恢复成功率 Lipschitz 常数 L_r
        p_lb_real = max(0.0, p_lb - L_r * W1_est)
        if p_lb_real >= p_req and T_ub <= T_budget:
            frc[s0] = FRC(p=p_lb_real, T=T_ub, policy=policy_lib.id(s0))
        else:
            frc[s0] = UNKNOWN
    return frc
```

### IP-58：恢复阶梯的约束选择（拒绝独立乘积假设）
```
def select_recovery_ladder(s, fault, frc, budget):
    best = None
    for seq in ladder_sequences(R0, R1, R2, R3, R4, max_len=3):
        c   = sum(cap_loss[r] for r in seq)
        rho = max(switch_risk[r] for r in seq)
        # 级联成功率下界用 Fréchet：max_i p_i^LB（不假设独立）
        p   = compose_success_lower_frechet(seq, s, fault, frc)
        T   = compose_time_upper(seq, s, fault, frc)
        if c <= budget.cap and T <= budget.T and rho <= budget.rho \
           and p >= 1 - budget.delta:
            score = (p, -T, -c, -rho)
            if best is None or score > best[0]:
                best = (score, seq)
    # 默认绝不「继续赌」：降为停机 + 人工接管
    return best[1] if best else [R3, R4]
```

### IP-57：证书灰度发布（SPRT + 爆炸半径 + LKG + 两阶段提交）
```
def canary_rollout(cert_v, fleet, stages=(0.01, 0.05, 0.20, 1.0),
                   n_min=200, alpha=0.01, beta=0.10):
    lkg = fleet.certificate
    for p in stages:
        if p * len(fleet) * expected_fail_cost(cert_v) > fleet.risk_budget.remaining():
            return FROZEN("blast_radius")
        with two_phase_commit(fleet, cert_v, fraction=p):   # 全成功才提交
            while True:
                s = observe_slo(fleet, cert_v)
                if s.n < n_min:
                    continue
                if s.safety_violations > 0:                 # 安全一票否决
                    rollback(fleet, lkg)
                    return ROLLED_BACK("unsafe")
                d = sprt(s, H0="ok", H1="regress", alpha=alpha, beta=beta)
                if d == REJECT:
                    rollback(fleet, lkg)
                    return ROLLED_BACK("regress")
                if d == ACCEPT:
                    break
        fleet.risk_budget.consume(p, s)
    lkg = cert_v
    return PROMOTED
```

## 3. 关键推导与正确性

**命题 3（恢复保证的 Sim-to-Real 传递）**：设恢复成功率作为状态-动作分布的泛函在 W_1 下 Lipschitz 连续，常数 L_r；第 42 轮已估 W_1(D_real,D_sim) ≤ ε_w。则在 D_sim 上以置信 1−δ_p 有 p_real ≥ p_sim^LB − L_r·ε_w。若恢复时间分位上界以 1−δ_T 成立，则由并集界，FRC 在实机成立的概率至少 1−δ_p−δ_T−δ_w。**含义**：FRC 的实机保证必须同时扣掉「采样不确定性」和「迁移不确定性」，不能只报仿真成功率。

**命题 4（级联恢复的保守界）**：对阶梯序列 π=(r_1,…,r_k)，若各级可能共享同一故障源，则成功事件是并集 ∪A_i，Fréchet–Hoeffding 给出 max_i p_i ≤ P(∪A_i) ≤ min(1, Σ_i p_i)。因此**可靠下界取 max_i p_i^LB**；常见的 1−∏(1−p_i) 只在独立假设下成立，不能作为安全证书。若需更紧界，必须标定故障相关性矩阵并显式计算联合分布，否则一律按最保守处理。

**命题 5（灰度发布的风险上界）**：若每个阶段满足 BR(p_k) ≤ B_remaining，且任一安全违例立即回滚到 LKG、回滚时间 ≤ T_rb，则单次坏发布的期望受影响机器人 ≤ p_max·N_fleet，期望暴露时长 ≤ T_detect + T_rb。**含义**：灰度不是「小规模试试」，而是把爆炸半径和暴露时长都写进可审计的不等式。

**命题 6（恢复不劣于 SafeStop 的条件）**：若 FRC 要求恢复全程 x_t∈S_weak，且 S_weak ⊆ S_safe^hard（硬件安全内核的硬安全集），则任何被 FRC 允许的恢复动作都不会比 SafeStop 更危险；反之，若 S_weak 越出硬安全集，恢复可能引入新的危险，必须禁止。这条把「恢复」与「安全内核」的边界钉死。

## 7. 本轮最大风险

**一句话**：恢复引擎把「停」换成「救」，但恢复本身是样本更稀少的新风险源——若 FRC 在训练分布外高估成功率、或灰度与遥测不完整导致过早重认证与恢复抖动，机器人会以「正在恢复」的名义进入比 SafeStop 更危险的状态；因此 E87（假认证率）与 E89（灰度回滚/爆炸半径）必须设为红线，任一失败即冻结发布并回退 LKG。
