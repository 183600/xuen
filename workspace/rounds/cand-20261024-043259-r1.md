# 本轮 · JADE：云边双频、关节残差、双动作空间

> 检索/复核日期：2026-10-24（UTC）。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署、官方远程真机 API 评测。本轮三个灵感词是「云边协同」「关节驱动」「动作空间」。我的主判断是：**当前 VLA 的瓶颈不在“看懂任务”，而在“最后一厘米的接触调节”——单一体、单动作空间、单频率的策略，隔着网络延迟去控制一个需要力/位混合的接触过程。把云端的语义规划与边缘的关节执行拆开，把 EE 子目标与关节动作拆开，再用关节跟踪残差当“免费的接触观测器”，是同时回应三个灵感词、且能在 8 周内落地的主线。**

先纠正上一轮的两个偏差，再补两个本轮新事实，否则后面的预算会继续算错。

## 0. 本轮先钉住四件事

### 0.1 排名是“成功率优先”，不是“成功率 + 步骤分综合排序”

官方手册写得很清楚：实时榜单按 **32 个任务的总平均成功率** 排序；成功率相同时才按 **总平均步骤分** 排序；仍相同则提交日期早者靠前（[S1][S2]）。上一轮把两者当成综合目标，会诱导“为了过程分做很多半成品动作”。本轮改为：

```text
第一目标：成功率（全部步骤完成）
第二目标：仅在同成功率时，步骤分才决定名次
步骤分的新用途：诊断“倒在哪一步”，不是优化目标
```

这意味着：**任何不能把“最后一步完成率”抬上去的改动，都不应该占用主预算。** 过程分高但成功率不高的方案，在排行榜上没有价值。

### 0.2 榜单仍是 teaser，只能当难度先验

`leaderboard.html` 仍显示“即将发布”，表格被模糊遮罩；`leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`；详情页视频仍写“测试视频占位”；`runs.html` 是 256/256 占位（[S3][S4]）。但 Jina 能渲染出 8 个模型的 teaser 表，且 `task_metrics` 结构完整（[S4]）。我把它当“未官宣的难度先验”，不当真实对手：

| 模型 | 队伍 | 成功率 | 步骤分 | 平均时长 |
|---|---|---:|---:|---:|
| MolmoAct2 | DexHacker | 29.7% | 39.0% | 44.02s |
| WALL-OSS-0.5 | Generalist Robotics | 28.5% | 38.9% | 43.74s |
| DreamZero | World Model Lab | 27.9% | 37.9% | 44.59s |
| Spirit-v1.5 | VLAGO | 25.9% | 34.4% | 45.19s |
| DM0 | Embodied AI Institute | 23.5% | 31.7% | 45.11s |
| PI-0.5 | RoboReasoner | 22.8% | 30.6% | 43.88s |
| GigaBrain-0 | xembody | 22.6% | 29.5% | 43.76s |
| GR00T N1.5 | Humanoid Dynamics | 20.5% | 28.1% | 44.71s |

三个可用的观察（都标“未核实”）：

1. **步骤分比成功率平均高 8.59pp**（33.76 vs 25.17）。如果真实榜单也是这个结构，失败主要发生在“做完大部分步骤、倒在最后一步”，而不是“完全不会”。
2. **头部差距很小**：29.7 / 28.5 / 27.9，前三名只差 1.8pp；32 任务 × 10 次 = 320 个 episode，p≈0.25–0.30 时二项标准误约 2.4–2.6pp。**前三名在统计噪声内**，不是三个明确的技术档次。
3. **没有单一模型全面领先**：32 个任务的最优模型分散在 8 个模型里（MolmoAct2 8 项、WALL-OSS 7 项、DreamZero 6 项、Spirit 5 项、DM0/PI-0.5 各 2 项、GR00T/GigaBrain 各 1 项）。这说明“押一个更大的通用模型”不是唯一解，**执行层/接触层的差异可能比语义层更大**。

最难的 5 项（8 模型平均成功率）是：Plug In Ethernet 17.7%、Unlock 20.1%、Spell robot 21.8%、Organize Stationery 22.5%、Open Pill Bottle 22.7%；较易的 Stack Cups 30.3%、Conveyor Food Sorting 29.1%、Paper Cup Stacking 28.0%。困难项几乎都含**插入、拧转、闭合、对位、释放**——典型的接触密集阶段。

### 0.3 180s 不是瓶颈，失败不是“时间不够”

teaser 的平均时长约 44.4s，远低于 180s 上限；HangCup 官方演示的中位时长约 5.9s（94–411 帧，30fps）。如果真实数据接近，**大多数失败不是超时，而是动作做完但任务没完成**。这给“接触段重试、落点校验、二次抓取”留出了充足预算，也说明 180s 应该被当作“重试预算”，而不是“慢慢推理的借口”。

### 0.4 官方数据确实同时有“关节动作”和“EE 动作”

我下载并审计了 HangCup 的 `file-000.parquet`（130,565 帧、719 条 episode、30fps；[S9][S10]）：

- `observation.state.left_arm/right_arm` 是 7 维关节位置；`action.left_arm/right_arm` 是 7 维关节目标；
- 同时存在 `action.left_ee_pose_gripper_base` / `right_ee_pose_gripper_base` 的 6 维 EE 目标（xyz+rpy）；
- 还有 `observation.state.left_ee_pose_gripper_base` 与 `right_ee_pose_gripper_base`，以及 base/torso 两套坐标；
- 四路相机、夹爪、`action.pivot`、下半身都在数据里。

这确认了“EE 规划、关节执行”不是空想：**训练数据里两种动作空间都有，可以显式学习它们之间的差**。更关键的是，我可以从 `a_t` 与 `q_{t+1}` 直接算关节跟踪残差：

```text
r_t = a_t - q_{t+1}                         # 关节目标与下一帧实到的差
ε_t = r_t - f(q_t, q̇_t, q̈_t, gripper_t)   # 扣掉运动滞后后的“残差新息”
```

在 HangCup 的 719 条 episode 上，右臂（主操作臂）的 `|r_t|` 中位数 0.051 rad、p95 0.140、max 0.826；`|r_t|` 与关节速度的相关系数 **0.783**，说明它主要被运动滞后支配，不能直接当力。用 `q, q̇, q̈, gripper` 做逐 episode held-out 的岭回归后，R²=**0.509**，残差新息 `|ε_t|` 中位数降到 0.039、p95 0.068。也就是说，**扣掉可预测的运动滞后后，仍有一部分结构化的“新息”**；这部分才可能是接触/释放/扰动。

我用“夹爪状态翻转”当接触代理标签（±0.1s，held-out episode）做了一个快速检验：只用 `|r|, ||r||, |ε|, ||ε||, ||q̇||, ||q̈||`，预测“释放”事件的 AUC 为 **0.889**；加入夹爪/运动特征后 AUC 0.971；只给夹爪+运动特征是 0.960。结论不是“残差等于力”，而是：**残差里确实有夹爪命令之外的接触/释放信息，值得做成一个观测器**。这个证据只来自 HangCup、标签是代理标签，必须跨任务复核（见产物区 §5）。

## 1. 三个灵感词，各自钉到官方约束上

### 1.1 云边协同：不是“把模型放云上”，而是“把延迟变成结构”

官方约束（[S1][S5][S6]）：

| 约束 | 事实 | 设计含义 |
|---|---|---|
| 远程 API | 官方不跑模型，只远程调用选手服务 | 推理延迟、网络抖动、并发都是方案的一部分 |
| 动作 chunk | `get_action` 返回一个 chunk，评估端执行完再调用 | 延迟至少是一个 chunk 的执行时间；接触段需要短 chunk/快速纠正 |
| N 台机器人 | N 个连续端口，从 8765 起，数量必须精确匹配 N | 不能假设单实例；共享后端要处理并发与状态隔离 |
| 算力自备 | 官方不提供模型运行机器 | 可以用“云 GPU + 边缘端点”的异构部署；云模型可跨端口共享 |
| 交互质量 | 每步延迟、动作统计会被记录，评估平滑性/异常 | 不能靠抖动/突发动作骗过接触；边缘执行器要平滑 |

所以“云边协同”在这里不是把 VLA 放云上就完事，而是：

```text
云：大模型、慢频、语义/子目标、可跨 N 端口共享
边：小计算、快频、当前观测、每端口独立状态、接触调节
```

这同时解决两个现实问题：**大模型不必复制 N 份**；**接触段不必等云端大模型**。

### 1.2 关节驱动：G1 的关节不是“动作维度”，是“接触观测器”

G1 的 7-DoF 手臂 + Dex1 夹爪，官方数据给的是关节目标/关节状态，不是力矩。没有力/触觉传感器时，最接近“力”的信号是**关节跟踪误差**：当夹爪/手指碰到物体、插入卡住、物体被拿走，关节实际位置会偏离指令。这个偏差在自由空间主要来自伺服滞后，在接触段会出现额外的、方向性的新息。把它建模成：

```text
r_t = q_cmd,t-1 - q_t
ε_t = r_t - f_motion(q_t, q̇_t, q̈_t, gripper_t)
```

`f_motion` 可以是一个很小的动力学/回归模型（不是第二个通用策略），用来扣掉“速度/加速度造成的滞后”。剩下的 `ε_t` 用于：

- 接触/释放检测：`c_t = P(contact | ε_t, q̇_t, gripper_t)`；
- 柔顺：接触时把位置增益降下来，允许 `q_des = q* + A ε_t` 的微小偏转；
- 失败恢复：如果 `c_t` 高但任务谓词不满足，触发重试/换抓/换路径；
- 扰动检测：人为移动物体时，残差会出现与计划不一致的突变。

这里的关键是“**用关节驱动本身产生接触信息**”，而不是额外装传感器。对比赛来说，这是合规且零硬件成本的。

### 1.3 动作空间：EE 与 joint 不是二选一，而是两层

官方 API 的动作空间是互斥的：`control_space` 只能选 `joint` 或 `ee`（[S6]）。这看起来是限制，实际上给了两种互补的归纳偏置：

| 空间 | 优势 | 劣势 | 适合 |
|---|---|---|---|
| EE（base 系 xyz+rpy） | 跨物体/跨背景/跨具身泛化好；相对位移直观；不受 IK 冗余影响 | 接触段由底层 IK 硬扛；难表达柔顺/关节限位；残差不可控 | 自由空间接近、抓取前对位、语义子目标 |
| joint（7 维关节目标） | 可直接做关节限位、速度限制、柔顺/admittance；残差可直接观测；平滑 | 与具身强绑定；跨任务泛化弱；直接学绝对关节目标难 | 接触、插入、拧转、闭合、释放、退出 |

近期证据也支持“EE 相对动作更适合跨具身泛化”（[S11]），但接触密集任务又需要关节空间的柔顺与约束。上一轮把动作空间当“提交时选一个”，本轮改为：

> **对外声明 `joint`；内部用 EE 做慢频子目标，用 joint 做快频执行；EE 只是内部表示，不违反 API 的互斥约束。**

这不是“两个模型”，而是**一个策略系统的两层动作表示**：云端输出 EE 子目标，边缘用 IK + 关节约束把它变成 joint 目标；最终 API 只看到 joint。合规上，只有一个学习 checkpoint；边缘是确定性控制代码（见 §6）。

## 2. 主判断：瓶颈是“语义-物理间隙”，不是语义本身

### 2.1 一个更锋利的失败模型

把 32 个任务拆成三段：

```text
A. 语义/定位：去哪个物体、放到哪、当前哪一步   → VLA/视觉语言
B. 自由空间运动：接近、抓取前对位、搬运         → EE 相对动作较合适
C. 接触/终局：插入、拧转、闭合、堆叠、释放、撤出 → 关节柔顺 + 接触反馈
```

teaser 的“步骤分高、成功率低”与“困难任务集中在 C 段”指向同一个假设：**A/B 段已经能拿到大部分过程分，C 段把成功闸门卡住了。** 这不是“模型不够大”的问题；再大的 VLA 如果仍然用单频率、单空间、开环 chunk 去撞接触，也会在最后一厘米丢分。

### 2.2 三个可证伪假设

- **H1（云边分解）**：云端 VLA 只负责 EE 子目标/步骤谓词，边缘高频执行，能在不增加云端推理频率的情况下，把接触段反应时间缩短到 chunk 以内。
- **H2（关节残差）**：扣掉运动滞后后的关节残差新息，能在夹爪命令之外提供接触/释放信息；用它可以减少“假完成”和“接触过冲”。
- **H3（成功优先）**：在 180s 内做谓词校验 + 有限重试，能把一部分“过程分高但终局失败”的 episode 转成成功；收益大于继续优化过程分。

三个假设都可以用官方数据离线检验，再用单任务调试槽做小规模真机 A/B。任何一个不成立，主方案降级（见 §6）。

### 2.3 为什么不是“再训一个更大的 VLA”

- 算力自备，官方不提供训练/推理机器；更大模型的边际收益不确定。
- teaser 里 8 个模型差距在统计噪声内，说明“换更大 backbone”不是稳定 gain。
- 真正的差异化在**执行层**：同样一个 VLA，接触段怎么执行，可能决定 10pp 的成功率。
- 云边结构可以把“大模型”放在云端共享，不必为 N 个端口复制 N 份；这是工程上可持续的。

### 2.4 预期杠杆（先给可证伪的数）

设 `q` 为“到达最后接触段”的比例。若 `q≈0.6`，接触段成功率提升 15pp，则整体成功率约 +9pp；若 `q≈0.4`，则约 +6pp。这是**估算，不是承诺**。对应的 falsification：在 HangCup / PlugCharger / StackBowls 三个调试任务上，如果 JADE 相对 cloud-only 基线的全任务成功率提升 <5pp，或“到达最后一步但失败”的比例没有下降 30%，则 H1/H2 不成立，回退到纯 EE + 重试。

## 3. JADE 轮廓

**JADE = Joint-space Admittance Dual-rate Executor**（关节空间柔顺、双频执行器）。名字里的三个词分别对应：Joint（关节驱动/残差）、Admittance（接触柔顺）、Dual-rate（云边双频）。

```text
┌────────────────────────── Cloud（慢频，1–5 Hz）──────────────────────────┐
│  延迟观测 o_{t-δ} + 语言 l                                                │
│        │                                                                 │
│        ▼                                                                 │
│  单一 VLA checkpoint（MolmoAct2 / WALL-OSS / π0.5 / GR00T 候选）          │
│   ├─ EE 子目标头：g_t = (Δx, Δrpy) 或 base 系目标位姿                    │
│   ├─ 步骤谓词头：当前步骤 s_t、完成概率、失败概率                         │
│   └─ 接触先验头（可选）：从延迟视觉/本体预测接触阶段                       │
│        │  timestamped subgoal + predicate                                 │
└────────┼─────────────────────────────────────────────────────────────────┘
         │  异步队列（可丢旧帧、可插值）
┌────────▼──────────────── Edge（快频，10–30 Hz，每端口独立）──────────────┐
│  当前观测 o_t（四路 RGB + 双臂关节 + EE + 夹爪）                          │
│        │                                                                 │
│        ├─ IK/约束层：g_t → q*_t（关节限位、速度限制、最小 jerk）           │
│        ├─ 残差观测器：r_t = q_cmd,t-1 − q_t；ε_t = r_t − f_motion(...)     │
│        ├─ 接触分类/阈值：c_t = P(contact | ε_t, q̇_t, gripper_t)            │
│        ├─ 仲裁器：自由空间走 q*_t；接触段走 q*_t + A ε_t（柔顺）           │
│        └─ 输出：joint chunk（action.left_arm/right_arm + gripper + pivot） │
└────────┬─────────────────────────────────────────────────────────────────┘
         │
         ▼
  评估端执行 joint chunk；下一步把新观测送回 edge
         │
         ▼
  成功谓词 Ψ(s_t)：完成→停；未完成且预算足→重试/换抓/换路径；预算不足→安全退出
```

### 3.1 组件一句话

| 组件 | 作用 | 是否学习 |
|---|---|---|
| C1 云端 EE 子目标 | 把语义/视觉变成“去哪、什么姿态、哪一步” | 是（唯一 checkpoint 的一部分） |
| C2 边缘 joint 执行器 | IK、限位、速度/加速度约束、平滑 chunk | 否（确定性） |
| C3 残差接触观测器 | 用关节跟踪新息估计接触/释放/扰动 | 可校准统计量；严格合规时并入 C1 的头 |
| C4 动作空间仲裁 | 自由空间 EE 子目标，接触段关节柔顺 | 否（规则/阈值） |
| C5 成功优先 anytime 循环 | 谓词校验、重试预算、失败恢复 | 否（状态机） |
| C6 N 端口云边服务 | 云模型共享、边端点隔离、并发/超时 | 否（工程） |

### 3.2 关键公式

```text
# 1) 云端子目标（EE，base 系或相对当前 EE）
g_t = π_cloud(o_{t-δ}, l, s_t)

# 2) 边缘关节参考（IK + 约束）
q*_t = IK(g_t; q_t)  s.t.  q_min ≤ q* ≤ q_max, |q*−q_t| ≤ v_max·Δt

# 3) 关节残差与新息
r_t = a_{t-1} − q_t
ε_t = r_t − f_motion(q_t, q̇_t, q̈_t, gripper_t)

# 4) 接触概率（校准阈值/逻辑回归/单模型辅助头）
c_t = σ(w^T φ(ε_t, q̇_t, gripper_t))

# 5) 仲裁后的关节目标
q_des,t = q*_t + 1[c_t > τ] · A · ε_t      # A 为柔顺增益，带死区/限幅
a_t = clip(q_des,t, q_min, q_max)
```

`A` 不是越大越好：它只在接触段打开，且用残差的方向/幅值限幅，避免“把伺服滞后当成力”导致振荡。`f_motion` 可以先用岭回归/小 MLP；如果严格单模型，就把它固定成标定表，或把 `c_t` 作为 C1 的辅助头输出，边缘只做阈值。

### 3.3 动作空间仲裁：不是切换 API，而是切换内部参考

- 对外 `control_space="joint"`，永远返回 7 维关节目标；API 看不到 EE。
- 自由空间：`q*_t = IK(g_t)`，其中 `g_t` 来自云端 EE 头；这保留了 EE 相对动作的泛化优势。
- 接触段：在 `q*_t` 上叠加 `A ε_t`，并降低位置增益；这就是“关节空间 admittance”的离散实现。
- 退出接触：`c_t` 下降 + 谓词满足 → 回到自由空间；若谓词不满足 → 重试。
- 不需要在 episode 中切换 `control_space`，因此不违反互斥约束。

### 3.4 云边双频：把“旧子目标”变成可控变量

云端输出带时间戳的 `g_{t:t+H}`；边缘维护一个短 buffer：

- 若最新子目标年龄 < `T_fresh`：直接用；
- 若年龄在 `[T_fresh, T_stale]`：用最后有效子目标 + 关节参考的速度外推，并降低增益；
- 若年龄 > `T_stale`：进入“保持/微调”模式，不执行大动作；同时云端请求新子目标；
- 新子目标到达时，用最小 jerk 混合，避免 chunk 边界抖动（RTC 的思想，[S12]）。

这比“每步都等云端”更稳，也比“完全开环执行旧 chunk”更安全。接触段则进一步缩短 chunk/提高边缘频率；由于 `action_chunk_size` 在 metadata 里固定，默认取 **1–4**（用调试槽校准），并在边缘做逐帧平滑。

### 3.5 成功优先的 anytime 循环

```text
for each step s:
    run JADE until predicate Ψ_s true or budget_s exhausted
    if Ψ_s true: advance s
    else if budget left: retry (re-grasp / re-approach / alternate pose)
    else: safe abort
```

`Ψ_s` 来自公开评分步骤（例如“杯子挂到标记点”“插头插入插排”“拉链闭合”），用视觉 + 关节残差 + 夹爪状态共同判断。**过程分只用于诊断，不用于决定是否继续**；如果一步失败但还有时间，优先重试而不是“把剩下的步骤走完拿过程分”。

## 4. 与现有工作的差异

| 工作 | 做了什么 | JADE 的不同 |
|---|---|---|
| CloudEdgeVLA（[S13]） | 云端慢特征 + 边缘轻头，学习延迟不变表示；LIBERO 40-step 延迟下 63.8–78.0% | 我们把“动作空间/频率”显式拆开：云端 EE 子目标，边缘 joint 执行；并加入关节残差接触观测 |
| RTC（[S12]） | 异步执行 action chunk，冻结已执行前缀、inpaint 剩余 | RTC 解决 chunk 边界/延迟；JADE 解决“接触段该用什么空间、怎么知道接触了” |
| 关节本体感知（[S14][S15]） | 用关节/视觉推断接触，做灵巧手/在手机器人 | 我们把关节残差用于桌面 VLA 的接触段仲裁与重试，且不需要额外触觉硬件 |
| 动作空间 scaling（[S11]） | EE 相对动作对跨具身迁移关键 | 我们同意 EE 用于泛化，但主张接触段用 joint；两者是层次关系，不是二选一 |
| MolmoAct2 / WALL-OSS / π0.5 / GR00T（[S16]–[S19]） | 开放 VLA/世界模型 backbone | 我们不做“更大的 backbone”，而是做可插拔的执行层；backbone 可替换 |

一句话差异：**别人把云边当“延迟工程”，把关节当“动作维度”，把动作空间当“提交选项”；JADE 把三者合成一个接触感知的执行架构。**

## 6. 风险、合规与开关

- **排名风险**：始终以成功率为第一目标；任何“提高过程分但降低成功率”的改动一律回退。
- **单模型合规**：只保留一个学习 checkpoint（云端 VLA）；边缘 IK/限位/仲裁是确定性代码；残差检测优先用标定统计量。若官方认为辅助头/分类器也算第二模型，则把接触头并入同一 checkpoint，或只用阈值规则（见产物区 §7）。
- **外部数据/权重**：手册 2.2 之后未读到；默认只用官方 33k 数据训练/微调。使用 MolmoAct2/WALL-OSS/π0.5/GR00T 初始化是“条件开关”，需先确认规则。
- **N 端口**：不能假设 N=1；云端共享 + 边缘每端口独立状态；每端口 `reset()` 必须清空历史、残差 buffer、接触状态。
- **延迟/抖动**：旧子目标可能让接触段过冲；用 `T_fresh/T_stale` 和增益调度，不用“旧 chunk 硬执行”。
- **残差误判**：自由空间快速运动会产生大残差；必须做运动补偿 + 速度门控；接触段才打开柔顺。
- **安全**：关节限位、速度/加速度限制、力/残差超限退出；不要把“柔顺”做成“失控”。
- **数据偏差**：HangCup 是单任务、右臂为主；跨任务/双臂/透明物体/布料要分桶验证。
- **接口错位**：评测 API 的相机名是 `cam_left_high` 等，数据集是 `head_stereo_left` 等；EE 只有 base 系。训练时必须只用人 API 可用的键，或做显式映射/裁剪（见产物区 §1.4）。
- **时间预算**：180s 是重试预算，不是推理预算；单步延迟要有 p95 上限，避免“越想越慢”。

## 7. 一句话押注

**不再和榜单比“谁的 VLA 更大”，而是把比赛当成一个延迟受限的接触控制问题：云端 VLA 只负责 EE 子目标与步骤谓词，边缘用关节执行器把最后一厘米做成可柔顺、可检测、可重试的闭环；关节跟踪残差就是那个不花钱的接触观测器。**

### 1.5 关节残差实测（本轮新增）

对右臂，定义：

```text
r_t   = a_t − q_{t+1}                       # 目标与下一帧实到
ε_t   = r_t − f_ridge(q_t, q̇_t, q̈_t, g_t)   # 运动补偿后的新息
```

其中 `f_ridge` 用 `q, q̇, q̈, 夹爪指令/状态` 的线性特征，按 episode 80/20 划分训练，λ=1。

| 指标 | 数值 |
|---|---:|
| `abs(r_t)` 中位 / p90 / p95 / p99 / max | 0.0513 / 0.1165 / 0.1398 / 0.1926 / 0.8263 rad |
| `abs(r_t)` 与关节速度相关 | 0.783 |
| 岭回归 held-out R²（7 维联合） | 0.509 |
| `abs(ε_t)` 中位 / p90 / p95 / p99 / max | 0.0388 / 0.0588 / 0.0684 / 0.1005 / 0.4474 rad |

**解释**：原始残差主要被运动滞后支配，不能直接当力；扣掉可预测部分后，新息的 p95 从 0.140 降到 0.068（约 51%），且仍有长尾。长尾就是接触/释放/扰动的候选信号。

**代理事件检测**：以夹爪状态翻转（开/关）±0.1s 为正样本，held-out episode 逻辑回归：

| 特征 | 释放（open）AUC | 释放 AP | 关闭（close）AUC | 关闭 AP |
|---|---:|---:|---:|---:|
| 仅残差/运动（`abs(r), norm(r), abs(ε), norm(ε), norm(dq), norm(ddq)`） | **0.889** | 0.289 | 0.871 | 0.301 |
| 夹爪+运动（baseline） | 0.960 | 0.688 | 0.955 | 0.759 |
| 残差+夹爪+运动 | **0.971** | 0.721 | 0.962 | 0.739 |

测试集 25,592 帧，其中释放正样本 1,104 帧（约 4.3%），关闭正样本 1,058 帧。**结论**：残差在夹爪命令之外仍有增量信息（AUC 0.960→0.971），且单独使用也有 0.889；但它不是力传感器，标签也不是真实接触。必须跨任务验证。

|---|---|

## 2. 问题定义

### 2.1 延迟-接触耦合

评测端通过网络调用策略，策略返回 chunk，评测端执行完再调用。接触过程的时间尺度可能只有几十毫秒，而云端 VLA 的推理可能是几百毫秒到数秒。单频、单空间的开环 chunk 在自由空间没问题，但在接触段会出现：

- 子目标过期：云端还在“接近”，实际已经碰到；
- 空间不匹配：EE 目标由底层 IK 硬执行，遇到接触时位置误差变成大力；
- 无接触反馈：夹爪闭合/释放/插入深度没有可靠的闭环；
- 假完成：动作做完了，但物体没挂上/没插进/没拉上，过程分拿到了，成功率没有。

### 2.2 三类失败模式

| 失败 | 表现 | JADE 对策 |
|---|---|---|
| F1 子目标过期 | 旧 EE 目标继续推，过冲/撞 | 时间戳 + 新鲜度分级 + 速度外推/保持 |
| F2 接触过硬 | 插入卡住、堆叠弹开、释放拉扯 | 残差触发 admittance，降低位置增益，允许微小偏转 |
| F3 假完成 | 过程分高、成功率低 | 谓词校验 + 残差/视觉复核 + 重试 |

### 2.3 设计目标

1. **成功率优先**：所有组件服务于“完成全部步骤”，不是“多拿过程分”。
2. **单一 checkpoint**：云端 VLA 是唯一学习模型；边缘确定性；无任务路由。
3. **延迟可生存**：云端慢频、边缘快频；旧子目标有安全策略。
4. **接触可观测**：只用 API 可见的关节/夹爪/图像，不假设力/触觉。
5. **合规可审计**：动作空间、模型数量、数据来源、N 端口都有明确开关。

## 3. JADE 架构

### 3.1 总览

```text
┌──────────────────────── Cloud（1–5 Hz，跨端口共享）────────────────────────┐
│  o_{t-δ}（降采样图像 + 语言 + 稀疏状态）                                   │
│      │                                                                    │
│      ▼                                                                    │
│  单一 VLA checkpoint                                                       │
│   ├─ EE 子目标头：g_t = ΔEE 或 base 系位姿                                │
│   ├─ 步骤谓词头：s_t、p(done)、p(fail)                                     │
│   └─ 接触先验头（可选）：p(contact | 延迟观测)                             │
│      │  timestamped g_t, s_t                                              │
└──────┼─────────────────────────────────────────────────────────────────────┘
       │ 异步队列：只保留最新 K 个；旧帧可丢
┌──────▼──────────────── Edge（10–30 Hz，每端口独立）───────────────────────┐
│  o_t（四路 RGB + 双臂关节历史 + EE + 夹爪）                                │
│      │                                                                    │
│      ├─ IK + 约束：g_t → q*_t（限位/速度/加速度/最小 jerk）                 │
│      ├─ 残差：r_t = a_{t-1} − q_t；ε_t = r_t − f_motion(...)               │
│      ├─ 接触：c_t = σ(w^T φ(ε_t, q̇_t, gripper_t))                         │
│      ├─ 仲裁：q_des = q*_t + 1[c_t>τ]·A·ε_t                                │
│      └─ 输出 joint chunk（arm + gripper + pivot）                          │
└──────┬─────────────────────────────────────────────────────────────────────┘
       │
       ▼
  评估端执行 → 新观测 → 谓词 Ψ(s_t)
       │
       ├─ 完成：停
       ├─ 未完成且预算足：重试/换抓/换路径
       └─ 预算不足：安全退出
```

### 3.2 云端：EE 子目标 + 步骤谓词

**输入**：语言（32×5=160 条复述之一）、四路降采样图像、双臂关节/EE/夹爪的稀疏历史。  
**输出**：

- `g_t`：EE 子目标。两种参数化二选一：
  - 相对当前 EE 的增量 `(Δx, Δy, Δz, Δroll, Δpitch, Δyaw)`；
  - base 系绝对位姿 `(x, y, z, roll, pitch, yaw)`。
  训练时同时有 `action.*_ee_pose_gripper_base`，可直接监督；相对增量由相邻 EE 位姿差分得到。
- `s_t`：当前步骤索引（由公开评分步骤 + 语言/视觉推断）。
- `p(done)` / `p(fail)`：谓词头，用于触发重试/安全退出。
- 可选 `p(contact)`：接触先验，只作为边缘阈值的先验，不单独决定动作。

**为什么用 EE 头做云端**：EE 相对动作对跨背景/跨物体/跨具身更稳（[S11]）；云端不需要知道 G1 的具体关节配置，换 backbone/换机器人更容易。  
**为什么云端不直接输出 joint**：关节绝对目标与具身强绑定，跨任务泛化差；而且云端频率低，直接输出 joint 会在接触段过冲。

### 3.3 边缘：joint 执行器

**输入**：当前观测 + 最新 `g_t`。  
**步骤**：

1. **IK**：`q*_t = IK(g_t; q_t)`。7-DoF 冗余臂用阻尼最小二乘/零空间保持舒适姿态；若 IK 失败，回退到上一个可行 `q*` 并请求云端新子目标。
2. **约束**：关节限位、速度 `|Δq| ≤ v_max Δt`、加速度限制、最小 jerk；对 chunk 内轨迹做五次多项式/滑动平均。
3. **残差**：用上一帧实际下发的 `a_{t-1}` 与当前 `q_t` 计算 `r_t`；用 `f_motion` 扣掉运动滞后。
4. **接触仲裁**：`c_t` 超过阈值时，降低位置增益，叠加 `A ε_t`；否则纯跟踪 `q*`。
5. **输出**：`action.left_arm/right_arm`、`left_gripper/right_gripper`、`pivot`。`pivot` 在桌面任务中通常保持/微调，避免底座漂移。

**为什么边缘用 joint**：可以直接做限位/柔顺/平滑；残差可直接观测；API 允许。  
**为什么边缘不学一个大策略**：单模型合规；边缘要快；确定性代码可审计；残差检测用标定统计量即可。

### 3.4 残差接触观测器

#### 3.4.1 定义

```text
r_t = a_{t-1} − q_t
ε_t = r_t − f_motion(q_t, q̇_t, q̈_t, g_t)
```

`f_motion` 的第一版：逐关节线性/二次特征回归，特征包括 `q`、`q̇`、`q̈`、`sign(q̇)`、夹爪指令/状态、以及 `q̇` 与关节的交互项。用官方数据按 episode 划分训练/校准；不跨 episode 泄漏。

#### 3.4.2 接触概率

第一版用**校准的逻辑回归/阈值**，不用大网络：

```text
c_t = σ(w^T φ(ε_t, q̇_t, g_t))
φ = [|ε| (7), ||ε||, |r| (7), ||r||, ||q̇||, ||q̈||, gripper, 1]
```

阈值 `τ` 由自由空间（无接触阶段）的 `ε` 分布定：例如 `τ = p99(||ε||)` + 迟滞；接触段要求连续 2–3 帧超过阈值才触发，避免单帧噪声。

#### 3.4.3 三种用法

| 用法 | 规则 | 目的 |
|---|---|---|
| 释放检测 | `c_t` 高 + 夹爪从闭合到张开 | 确认“放下了”，而不是“还挂着” |
| 插入/接触 | `c_t` 高 + 末端速度低 + 位置误差持续 | 降低增益、微调/搜索、避免过冲 |
| 扰动/失败 | `c_t` 突变 + 视觉/谓词不一致 | 重新定位、重试、放弃当前轨迹 |

#### 3.4.4 与“力”的区别

残差不是力矩：它包含伺服滞后、摩擦、模型误差、关节柔度。我们只主张“**接触/释放的可观测代理**”，不主张“精确力估计”。因此：

- 不用残差做精确力控；
- 只用它做**模式切换/增益调度/重试触发**；
- 所有阈值用自由空间校准，接触段限幅；
- 跨任务必须重新校准；透明/布料/软物体单独分桶。

### 3.5 动作空间仲裁

| 阶段 | 内部参考 | 输出 | 理由 |
|---|---|---|---|
| 自由空间接近 | 云端 EE 子目标 `g_t` → IK `q*` | joint | EE 泛化好；joint 平滑/限位 |
| 抓取前对位 | `g_t` + 夹爪先验 | joint + gripper | EE 相对位姿；夹爪闭合用残差确认 |
| 接触/插入 | `q* + A ε` | joint | 柔顺、避免大力；残差触发 |
| 释放/退出 | `q*` + 缓慢张爪 | joint | 避免拉扯；残差确认释放 |
| 失败重试 | 重新 `g_t` / 换抓取点 | joint | 成功优先 |

**API 合规**：`control_space="joint"`，不切换；EE 只是内部变量。这样既拿到 EE 的泛化，又拿到 joint 的接触控制。

### 3.6 云边双频与延迟策略

```text
T_fresh = 150ms      # 子目标新鲜
T_stale = 500ms      # 超过则降增益/保持
```

- 云端异步：每 `1/f_cloud` 产生一个 `g_t`，带 `t_obs`、`t_recv`、`step`、`confidence`。
- 边缘每步取最新有效 `g_t`；若 `age = now - t_obs`：
  - `< T_fresh`：正常跟踪；
  - `[T_fresh, T_stale]`：用最后两个 `g` 的速度外推，增益 ×0.7；
  - `> T_stale`：保持最后可行 `q*`，不执行大位移；请求云端刷新；
  - 新 `g` 到达：最小 jerk 混合 3–5 帧，避免跳变。
- 接触段：`c_t` 高时进一步降低对旧 `g` 的信任，优先“保持 + 微调”，直到新 `g` 到达。
- 失败/超时：看门狗；超过 `T_watchdog` 没有有效 `g`，安全退出。

### 3.7 成功优先的 anytime 循环

```text
s = 0; budget = 180s - safety_margin
while s < S and budget > 0:
    execute JADE until Ψ_s true or step_budget exhausted
    if Ψ_s true:
        s += 1
    else:
        if budget > retry_cost(s):
            choose retry: re-grasp / re-approach / alternate pose / human-disturbance recovery
        else:
            safe_abort()
```

**谓词 `Ψ_s`**：来自公开评分步骤，如“杯子挂到标记点”“插头插入插排”“拉链闭合”“碗叠上”。用视觉 + 残差 + 夹爪状态联合判断；不确定时宁可重试，不要假完成。

**重试预算**：按任务步数和演示时长分配；长程任务（FoldTowel/OrganizeStationery/OrganizePencilCase）限制重试次数，避免超时。过程分只记录，不决定是否继续。

### 3.8 N 端口云边服务

```text
                    ┌──────────────┐
  evaluator :8765 → │ edge worker 0 │ ─┐
  evaluator :8766 → │ edge worker 1 │ ─┼→ cloud inference queue → 单一 VLA
  evaluator :8767 → │ edge worker 2 │ ─┘   （batch/continuous batching）
                    └──────────────┘
```

- 每个 edge worker：独立状态（历史、残差 buffer、接触状态、重试计数）；`reset()` 只清自己。
- 云端：一个模型实例 + 请求队列；支持并发/批处理；返回带 `episode_id`/`port` 的结果，杜绝串状态。
- 超时：每个端口独立 watchdog；云端排队超时则边缘进入保持/安全模式。
- 压力测试：N 端口同时发请求，检查 p50/p95 延迟、状态隔离、内存；N 的准确值未知，按 N=3/4/8 做阶梯测试。

## 4. 学习与训练配方

### 4.1 数据管线

1. **全 32 任务审计**：对每个数据集计算 episode 数、帧数、关节/EE/夹爪范围、残差统计、接触代理事件。输出“任务-残差画像”。
2. **API 对齐**：只保留 API 可见的键；相机名/分辨率/裁剪映射；EE 只用 base 系；动作只用 arm/gripper/pivot。
3. **云端 EE 监督**：由 `action.*_ee_pose_gripper_base` 生成绝对/相对 EE 目标；语言用 5 条复述；步骤标签由公开评分步骤 + 时间相位启发式生成。
4. **边缘残差标定**：按任务/臂/夹爪状态分桶，拟合 `f_motion`；用自由空间帧估计阈值；用夹爪翻转/视觉接触代理做验证。
5. **接触代理标签**：
   - 夹爪状态翻转（可靠、但只覆盖抓/放）；
   - 腕部图像中物体-夹爪相对运动（视觉）；
   - 任务相位（插入/拧转/闭合）；
   - 可选：人工标注少量调试槽视频。
6. **数据划分**：按 episode 划分，绝不按帧随机；跨任务留出验证；避免同一场景泄漏。

### 4.2 云端 VLA

**候选 backbone**（条件：外部预训练权重政策允许）：

- MolmoAct2（[S16]）：action reasoning、开放、部署优化；
- WALL-OSS-0.5（[S17]）：4B 级开放 VLA；
- π0.5（[S18]）：50-step/1s 连续关节 action chunk，高层文本 + 低层动作专家；
- GR00T N1.5（[S19]）：双系统 VLA，支持 joint/EE。

**训练策略**：

- 冻结视觉语言 backbone，训练 LoRA + EE 头 + 步骤谓词头；或全量微调（算力允许时）。
- 损失：EE 位姿回归（L1/L2 + 方向余弦）、步骤分类（CE）、完成/失败（BCE）、可选的接触先验（BCE）。
- 动作 chunk：云端输出未来 H 个 EE 子目标（H=8–16），边缘只取当前/最近一个；这样云端可以低频，边缘可以插值。
- 语言：覆盖 32×5 复述；中文描述只做数据增强/鲁棒性，不假设评测一定用英文。
- 图像：训练时用与 API 相同的相机名/分辨率/裁剪；随机背景/光照/位置增强要谨慎，避免与官方 5 轴冲突。

**如果外部权重不允许**：

- 用官方 33k 从零训练一个较小 VLA/扩散策略，或只用官方数据训练 EE 头 + 轻量 backbone；
- 优先保证“单模型 + 全任务”，不追求最大 backbone；
- 在产物中明确标注“条件方案”，不把外部权重当既定事实。

### 4.3 边缘执行器

- **IK**：G1 URDF + Pinocchio/TracIK；7-DoF 冗余，零空间保持肘部/腕部舒适；IK 失败回退。
- **约束**：关节限位、速度/加速度、jerk；chunk 内五次多项式；输出前限幅。
- **残差**：`f_motion` 第一版线性/二次；每个关节独立；按任务/臂校准；在线用最近 N 帧更新偏置（慢自适应，避免把接触学成偏置）。
- **接触**：逻辑回归/阈值 + 迟滞；自由空间校准；接触段限幅；失稳时退出柔顺。
- **重试**：状态机；记录每次重试的 `g`、`q`、`ε`、谓词结果，供离线分析。

### 4.4 算力预算（保守估计）

| 项 | 估计 | 说明 |
|---|---|---|
| 云端推理 | 1×24–80GB GPU | 3–14B VLA，降采样图像，chunk H=8–16 |
| 云端微调 | 4–8×A100 80GB，1–2 周 | LoRA/部分微调；若只训练头，需求更低 |
| 边缘 | 每端口 1–2 CPU 核 / 可选小 GPU | IK + 残差 + 滤波；N 端口线性扩展 |
| 存储 | 33k episodes + 特征缓存 | 视频较大，建议预提取/降采样 |
| 调试 | 单任务调试槽 + 本地回放 | 规则未明，预留时间/成本 |

> 注：以上是计划，不是已落实资源；如果算力不足，优先做“云端开源模型 + 边缘确定性执行”，不训练大模型。

| O4 | 双空间 vs 单空间 | 离线动作误差/接触段误差 | joint 执行 + EE 子目标优于纯 EE/纯 joint |
| O5 | 接触分类器 | AUC/AP/ECE、自由空间 FPR | AUC ≥0.80，FPR ≤5% |
| O6 | 谓词/重试回放 | 假完成率、重试收益 | 假完成率下降 ≥30% |

### 5.2 真机调试槽

任务选择（按接触类型）：

| 任务 | 接触类型 | 为什么选 |
|---|---|---|
| HangCup | 抓取 + 挂/释放 | 残差释放信号已初步验证 |
| PlugCharger | 插入/对位 | 典型接触密集、难度高 |
| StackBowls | 堆叠/放置 | 位置+释放+稳定性 |
| ZipUp | 闭合/拉链 | 长程接触、视觉/力混合 |

A/B 设计：

- 基线 A：cloud-only EE（或 cloud-only joint，取强者）；
- 基线 B：cloud-only + 谓词重试（无残差）；
- JADE：云边 + 残差 + 仲裁 + 重试；
- 每个任务 10–20 次，随机顺序，同一初始条件；记录成功、最后一步到达、残差事件、延迟、jerk。
- 先做 HangCup/PlugCharger（信息量最大），再扩到 StackBowls/ZipUp。

### 5.3 消融

| 消融 | 目的 |
|---|---|
| w/o residual | 残差是否真的贡献 |
| w/o arbitration（纯 EE） | 双空间是否必要 |
| w/o cloud（edge-only） | 云端语义是否必要 |
| w/o edge（cloud-only） | 边缘频率是否必要 |
| chunk size 1/4/8 | 延迟-反应 trade-off |
| 注入 0/150/300/600ms 延迟 | 云边鲁棒性 |
| `T_fresh/T_stale` 扫描 | 旧子目标策略 |
| 成功优先 vs 过程优先 | 排名目标是否正确 |
| N 端口并发 1/3/8 | 工程稳定性 |

### 5.4 统计

- 正式评测 320 episodes；p≈0.25–0.30 时 SE≈2.4–2.6pp；不要用单任务小样本外推。
- 调试槽用配对设计（同任务/同初始条件），任务级 bootstrap 置信区间；报告成功率和“最后一步到达率”。
- 与基线比较时，先看任务级配对差异，再看总体；避免被简单任务稀释。
- 如果只有 10 次/任务，单任务 SE 约 14pp，只能看大效应；把调试槽当“方向验证”，不当“排行榜预测”。

## 7. 创新点清单（持续迭代）

### I1 JADE 云边双频动作分解（新增，主押注）

- **动机**：远程 API + 接触段毫秒级反应 + 大模型低频，单频策略必然在接触段丢分。
- **差异**：CloudEdgeVLA 学“延迟不变特征”；JADE 显式拆“云端 EE 子目标 / 边缘 joint 执行”，并加入接触仲裁。
- **可行性**：API 允许 joint；云端可异步；边缘计算小；官方数据有 EE/joint。
- **资源**：1 个云端 GPU + N 个轻边缘；无需 N 份大模型。
- **步骤**：W2 云端 EE 头 → W4 集成 → W5 调试。
- **风险**：云端/边缘时钟/状态同步；旧子目标；规则是否允许分布式服务（应允许，但需确认）。
- **状态**：主押注。

### I2 关节残差接触观测器（新增，主押注）

- **动机**：无力/触觉传感器；关节跟踪残差是 API 自带的“免费信号”。
- **差异**：现有工作多用关节本体感知做灵巧手/在手机器人；JADE 用它做桌面 VLA 的接触段仲裁/重试。
- **可行性**：HangCup 实测 residual-only AUC 0.889；运动补偿 R²=0.509。
- **资源**：CPU 可算；逻辑回归/阈值；无需大模型。
- **步骤**：W1 残差审计 → W3 校准 → W4 集成。
- **风险**：残差主要被速度支配；跨任务/透明物体失效；需要分桶。
- **状态**：主押注，带降级开关。

### I3 EE→joint 双动作空间仲裁（新增，主押注）

- **动机**：EE 泛化好，joint 接触控制好；API 互斥，但内部可以分层。
- **差异**：动作空间 scaling 工作主张 EE 相对动作；JADE 主张“EE 规划 + joint 执行”，不是二选一。
- **可行性**：官方数据同时有 EE/joint；IK 可用 URDF；API 只看到 joint。
- **资源**：IK/约束 CPU；无需额外模型。
- **步骤**：W2 IK/约束 → W4 仲裁 → W5 验证。
- **风险**：IK 失败/奇异；EE 头误差放大；需要零空间/回退。
- **状态**：主押注。

### I4 残差驱动 admittance（新增，主押注）

- **动机**：接触段位置控制太硬；无力传感器时，用残差新息做柔顺。
- **差异**：传统 admittance 需要力/力矩；JADE 用关节残差代理，且只在接触段打开。
- **可行性**：`q_des = q* + A ε` 简单；限幅/死区可防振荡。
- **资源**：无额外硬件。
- **步骤**：W3 设计 → W4 集成 → W5 调参。
- **风险**：把伺服滞后当力；参数敏感；安全。
- **状态**：主押注，先保守增益。

### I5 成功优先谓词/重试（升级 SSG/SVL）

- **动机**：排名看成功率；过程分只 tie-break。
- **差异**：上一轮为过程分优化；本轮把谓词/重试作为成功率工具。
- **可行性**：公开评分步骤 + 视觉/残差/夹爪谓词；180s 预算。
- **资源**：状态机 + 视觉校验；CPU。
- **步骤**：W4 集成 → W5 调试。
- **风险**：谓词误判；重试超时；假完成。
- **状态**：高优先。

### I6 延迟感知旧子目标混合（新增，支撑）

- **动机**：云端子目标会过期；直接执行旧 chunk 会过冲。
- **差异**：RTC 解决 chunk 边界；JADE 增加“子目标年龄”分级和接触段降信任。
- **可行性**：时间戳 + 速度外推 + 最小 jerk。
- **资源**：边缘 CPU。
- **步骤**：W4。
- **风险**：外推过度；需要 watchdog。
- **状态**：支撑。

### I7 N 端口云边服务（新增，工程）

- **动机**：N 未知；不能复制 N 份大模型；状态必须隔离。
- **差异**：云端共享 + 边缘独立；针对官方端口规则设计。
- **可行性**：请求队列/批处理；每端口状态机。
- **资源**：1 个云端 GPU + N 个轻进程。
- **步骤**：W4 压测。
- **风险**：并发/超时/串状态；N 变化。
- **状态**：工程必做。

### I8 API 对齐数据管线（保留，支撑）

- **动机**：数据集键与 API 键不完全一致；训练/推理错位会直接失败。
- **差异**：显式映射相机/EE/动作；只用 API 可见键。
- **可行性**：已列出映射表（§1.4）。
- **资源**：数据工程。
- **步骤**：W1。
- **风险**：坐标系/裁剪/分辨率错位。
- **状态**：高优先。

### I9 开放 VLA backbone 适配（保留，条件）

- **动机**：从零训练不现实；开放 VLA 可加速。
- **差异**：JADE 把 backbone 当可插拔；不押单一模型。
- **可行性**：MolmoAct2/WALL-OSS/π0.5/GR00T 均有公开资料。
- **资源**：微调算力。
- **步骤**：W2。
- **风险**：外部权重政策未核实；许可/合规。
- **状态**：条件开关。

### I10 扰动触发重定位（新增，可选）

- **动机**：5 类泛化含人为干扰；残差突变 + 视觉变化可检测。
- **差异**：不是“重训抗干扰”，而是“检测到扰动→重定位→重试”。
- **可行性**：残差 + 视觉差异；状态机。
- **资源**：CPU。
- **步骤**：W6。
- **风险**：误触发；需要阈值。
- **状态**：可选。

### I11 接触数据引擎/校准（新增，支撑）

- **动机**：残差阈值/分类器需要跨任务数据。
- **差异**：用官方 33k + 代理标签，不依赖额外传感器。
- **可行性**：离线计算；分桶。
- **资源**：存储/CPU。
- **步骤**：W1–W3。
- **风险**：代理标签噪声；跨任务分布漂移。
- **状态**：支撑。

### I12 调试槽/TCLB（降级，流程）

- **动机**：真机反馈稀缺；调试槽是发布门。
- **差异**：从“主验证”降为“方向验证”；离线回放为主。
- **可行性**：平台单任务调试通道。
- **资源**：预约/时间。
- **步骤**：W5–W6。
- **风险**：次数/成本未知。
- **状态**：降级。

### 已砍/降级清单

- FLEET 作为“第六轴”研究框架（保留工程检查单：N 端口、并发、状态隔离、watchdog）。
- 全 32 任务高保真孪生（成本高、与接触段收益不直接）。
- 每任务 LoRA / task-specific router（违反单模型精神，且过拟合）。
- 自由仿真 RL / 运行时 MPC / 全物理布料拉链（8 周内不现实）。
- 以过程分为目标的优化（排名规则不允许）。
- 纯 EE 或纯 joint 的“站队”方案（JADE 的核心就是不要二选一）。

## 8. 风险、合规与开关

### 8.1 单模型合规

规则原文：“所有任务须基于同一模型完成，不得混合使用多个模型一起进行测试”（[S1]）。JADE 的解释与设计：

- **一个学习 checkpoint**：云端 VLA（含 EE 头、谓词头、可选接触头）完成全部 32 任务；无 task-specific 权重/router。
- **边缘不是第二个通用模型**：IK、限位、滤波、仲裁、阈值都是确定性控制代码；`f_motion` 是标定回归，不是通用策略。
- **接触检测**：优先用标定阈值/逻辑回归（传感器处理模块）；若官方严格认为任何学习分类器都算模型，则把接触头并入同一 checkpoint，边缘只接收其输出/只用阈值规则。
- **备选**：如果“云端 VLA + 边缘策略”被认定违反单模型，则把边缘学习部分全部去掉，保留确定性 IK/admittance/重试；这仍然是 JADE 的降级版。

### 8.2 外部数据/权重

- 手册 2.2 之后未读到；外部数据/预训练权重是否允许 **未核实**。
- 默认方案：只用官方 33k 数据训练/微调；外部开放 VLA 只作为“条件初始化”，先确认规则。
- 若不允许外部权重：优先训练小模型/头，或使用官方数据从零训练；不把 MolmoAct2/WALL-OSS 当既定依赖。
- 若允许外部数据：优先补“接触/插入/释放”片段，而不是无差别堆数据；注意与官方 5 轴分布对齐。

### 8.3 延迟/并发/状态

- 每端口独立 `episode_id`、历史、残差 buffer、接触状态、重试计数；`reset()` 彻底清理。
- 云端请求带 `port/episode/timestamp`；返回乱序时丢弃旧结果。
- 并发压测 N=1/3/8；p95 延迟、超时率、内存、状态串扰。
- 看门狗：云端无响应/边缘异常 → 保持/安全退出，不输出异常大动作。

### 8.4 接触/安全

- 关节限位、速度/加速度限制、jerk 限制；chunk 内平滑。
- 残差阈值带迟滞/连续帧确认；柔顺增益限幅；失稳立即退出。
- 不声称精确力控；不做高风险快速插入；调试槽先低速。
- 透明/软物体/布料：残差可能失效，分桶回退到视觉/纯位置 + 慢速。

### 8.5 数据/评估偏差

- HangCup 单任务、右臂为主；跨任务/双臂必须复核。
- 代理标签（夹爪翻转）不是真实接触；AUC 0.889 是“release 代理”，不是“插入接触”。
- teaser 数字未官宣；所有基于它的收益估计都标“未核实”。
- 调试槽样本小；不要用 10 次/任务的结果预测 320 episodes 排名。

## 9. 开放问题（按优先级）

1. **外部数据/预训练权重**是否允许？这决定 W2 是“微调开放 VLA”还是“从官方数据训练小模型”。
2. **N 的准确值**、控制频率、每步超时/重试规则；决定边缘 chunk size 和并发设计。
3. **单模型边界**：云端 VLA + 确定性边缘控制器是否合规？学习型接触分类器是否算第二模型？
4. **云边拆分**是否允许（选手自部署，应该允许；但需确认官方网络/端口只要求 N 个端点）。
5. **步骤分公式**：是否按步骤权重线性累加？是否有部分分/重复计数？影响谓词/重试预算。
6. **调试槽**次数、成本、可预约时间；决定 W5/W6 的实验规模。
7. **API 相机/坐标系**与数据集的精确对应（裁剪、内参、base 系定义）；决定 EE 头/IK 的误差。
8. **评测端动作执行频率**与 chunk 执行语义；决定 `action_chunk_size` 和 residual 的时间对齐。
9. **人为干扰的触发时机**是否可观测；决定扰动检测阈值。
10. **teaser 榜单**是否会在赛前更新为真实数据；决定难度先验的可信度。
