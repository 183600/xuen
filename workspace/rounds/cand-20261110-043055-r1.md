# 第 41 轮 · 结构优化 × 轻量化结构：载荷路径最小结构 v18（结构-资源共设计，四层架构 v6）

> 承接第 40 轮 v17（热预算 × 步数规划 × 学习-TO，Δ 资源平面）。本轮灵感词「结构优化 / 轻量化结构」。乍看是机械设计词，与只收 `PolicyService` 的赛题无关；但联网核实后我发现两条线在同一个问题上汇合：**v17 只会在运行时拧官方旋钮，却从未质疑「这套计算结构本身是否携带了过多寄生质量」**——正如轻量化机械结构的关键不是「少放材料」，而是「材料只放在载荷路径上」（F75/F76）。v18 的主轴：**用动作载荷路径做结构优化，把「单位物理成本的得分效率」从运行期治理推进到设计期共设计**；并对研究纲领自身执行同一套修剪（dogfooding）。

## 0. 联网核实（先事实后推理；检索口径 2026-11-10）

- **F67（VLA 专用 token 剪枝，arXiv 2511.16449 VLA-Pruner）**：VLM 的通用 token 剪枝按「语义显著性」保留 token，会系统性丢弃 action-critical 信息、显著损害 VLA；VLA 需要**双层重要性**——vision-language prefill 注意力（语义）+ action decode 注意力（动作，带时序平滑）。**推论：载荷度量必须以动作为准，不能沿用语义剪枝。**
- **F68（解耦早退，arXiv 2609.29382）**：把 VLM backbone 深度 V、action expert 深度 A、去噪步数 D 暴露为三个可联合配置的计算轴；最优预算**任务相关**；在 SmolVLA/π0.5 上延迟 −79.2%、FLOPs −31.8%、成功率 +5.6%，每处 exit 仅增 2.1%/4.1% 参数。**推论：结构优化应 task/scene-conditioned，而非一刀切。**
- **F69（A1，arXiv 2604.05672）**：训练无关的自适应早退，判据是相邻层 action chunk 的差异 Δa——「只在计算会改变动作时才计算」；LIBERO 推理时间 37.9s→10.5s（−72.3%），成功率 92.6%→96.4%，最多去掉 76.6% 层计算。**推论：动作改变量 Δa 就是最直接的「载荷」可观测代理，且可在推理期动态。**
- **F70（MoLe-VLA，AAAI 2026 / arXiv 2503.20384）**：Mixture-of-Layers 动态跳层，受 Shallow Brain Hypothesis 启发，说明动态深度在本体上可行。
- **F71（SparseVLM，ICML 2025，PMLR 267:74840–74857）**：视觉 token 稀疏化，LLaVA 上 FLOPs −54%、CUDA 时间 −37%、精度保持 97%。
- **F72（GRIP-VLM，arXiv 2605.13375）**：把 token 剪枝表述为 MDP，用 GRPO 直接搜索离散选择空间，预算感知、免重训，约 15% 加速。
- **F73（C-SWAP，arXiv 2510.18636 / BMVC 2025）**：**因果感知**的一次性结构化剪枝，用预测-结构的 cause-effect 关系渐进剪枝，无需微调。
- **F74（组件感知剪枝，arXiv 2504.13296 / IFAC J3C 2025）**：用依赖图隔离组件与组件间流，避免剪断跨组件参数组。
- **F75（多构件机械臂拓扑优化，Struct Multidisc Optim 68:188, 2025, DOI 10.1007/s00158-025-04129-1）**：BESO 在**时变载荷/多工况**下最小化平均柔度，计入自重与惯性载荷，并指出**运动策略与行程时间会反过来改变最优结构**——结构-运动必须共设计。**这是本轮最重要的跨学科迁移：载荷是工况相关的，不能只按名义工况优化。**
- **F76（腿部结构拓扑优化，arXiv 2507.16335）**：SIMP 变密度法，股骨减重 19.45%、整腿 7.92%，刚度/模态仍满足。
- **F77（QuietPrune，CVPR 2026）**：query-guided 早期 token 剪枝，2×2 半结构化分组，prefill 延迟最多 −19%，精度优于晚期剪枝。
- **F78（HiPrune，ACL 2026 Findings）**：层级注意力、免训练 token 剪枝，保留 anchor/buffer/register token。
- **F79（缺口与诚实记录）**：以上工作分别优化「token / 层深 / 去噪 / 剪枝 / 机械结构」，但**无人把感知 token、backbone 深度、action expert、去噪步数、TO 迭代、技能图放进同一物理预算下联合做结构优化**；无人用**动作干预载荷**作为闭环 VLA 的剪枝准则；也无人利用「内部动态结构」绕开官方 metadata 静态旋钮（F60）。G1 连杆柔度/URDF 仍未核实（A17/A38 延续）；**硬件改造是否合规未知（A39）**——所以物理结构优化只作 P2 顾问项，不作为得分依赖。

## 1. 研究者直觉（先直觉与动机，后形式化）

**直觉 0（先划边界：赛题只收软件，所以「结构」指计算结构）**。官方只接受 `PolicyService`（F60），我们不能改 G1 的连杆。因此「结构优化/轻量化结构」在本轮被**双重解释**：(a) **计算结构**——VLA 的 token/层/去噪/TO 迭代/技能图，这是可交付、可得分的主战场；(b) **物理结构**——轻量化会带来柔度与振动，控制必须「顺应」而非「对抗」，这是 P1 的精度抓手。把这两个解释分开，才不会把机械设计词硬套成空话。

**直觉 1（结构工程 → 载荷路径 vs 寄生质量）**。桁架之所以轻，不是因为材料少，而是因为材料都在载荷路径上；载荷路径之外的材料是「寄生质量」，只增加惯性、力矩和发热。VLA 完全同构：从观测到动作的因果路径之外的算力是「寄生算力」，只增加时延、热和失效面。但和桁架不同的是，**VLA 的载荷是随机的、工况相关的**——5 类泛化场景、不同任务阶段、未见物体/人为干扰会激活完全不同的子结构。F75 的核心教训正是：多构件臂必须按**时变多工况**优化，而不是单一名义工况；否则最优结构在别的姿态下就是坏的。所以本轮不做「名义载荷剪枝」，而做**多工况鲁棒结构优化**：保留名义+尾部都承重的结构，对「只在尾部承重」的结构降级为**储备结构**。

**直觉 2（轻量化 → 不是越小越好，而是刚度/质量比）**。机械轻量化的收益是惯量↓、力矩↓、发热↓（正好喂 v17 的 Δ-Plane），代价是柔度↑、振动↑、精度↓（正好打成功率）。F75/F76 都强调轻量化后仍要满足刚度/模态。于是 VLA 轻量化也不能只追 FLOPs：剪掉的结构若原本承担「稀有但致命」的动作修正，就会在长尾场景灾难性失效。正确目标不是最小，而是**最小充分结构（MSS）**：在全部场景桶上 E_score 不降的前提下，去掉一切非承重结构；并把「名义不承重、尾部承重」的部分保留为可再扩张的储备。

**直觉 3（VLA 特殊性 → 用语义剪枝会剪断动作载荷路径）**。F67 直接警告：VLM 通用剪枝按语义显著性选 token，会丢掉动作生成关键的信息；F69 更给出正确判据——**只在计算会改变动作时才计算**（Δa 早退）。所以载荷必须定义在**动作空间**：`L(v)=‖π(o)−π_{¬v}(o)‖`，即移除子结构 v 后动作改变多少。这把「结构优化」从经验剪枝升格为可测量、可证伪的因果问题，也天然兼容 F73（因果感知剪枝）与 F74（组件依赖图）。

**直觉 4（解决 v17 最大工程缺陷 → 把旋钮搬进网络内部）**。v17 自己承认：`obs_keys / image_resize / T_a / control_space` 都锁在 metadata，扰动场景无法动态调节（v17 风险表「旋钮半静态化」）。轻量化结构正好补这个洞：**token 骨架、层早退、去噪步数、TO 迭代上限都可以每步动态**。于是 v18 不只省算力，还把 v17 的静态旋钮风险转化为内部动态计算优势——这是本轮最硬、最可验证的技术收益，也是我最想在 E75 里证明的一条。

**直觉 5（对研究纲领自身做结构优化）**。v17 的 P0/升级模块已接近 20 项，接口多、验证面大、时延抖动源多。用同一把尺子量：哪些模块真正承重到「得分」？IP-42 跨本体（单 G1 平台用不上）、IP-44 MAML/课程（已 P2 或低边际）等是寄生质量；IP-48+IP-25+IP-45、IP-49+IP-39、IP-50+IP-35 则是同一载荷路径上的冗余接头。**每合并一个接口，就少一份时延抖动、少一个失效点**——这直接服务官方「时延平滑/动作规律」可信度条款（F60）。所以本轮同时也是「用结构优化修剪研究纲领」的一轮。

## 2. 灵感词 → 落地线（新增 + 合并 + 修剪）

- 「**结构优化**」→ **IP-51 LOAD-PATH-LIGHTVLA（P0 新增）**：动作载荷剖析（token/层/相机/去噪步/TO 迭代）→ 多工况鲁棒结构优化（SIMP 连续门控 + 因果重要性 + CVaR 尾部载荷）→ token 骨架（2×2 半结构化）+ 动态 V/A/D 早退 + 蒸馏；内部动态轻量化绕开 metadata 静态旋钮。**三分结构集：承重（全精度保留）/ 储备（低精度休眠、可再扩张）/ 寄生（剪除）。**
- 「**轻量化结构（物理侧）**」→ **IP-53 COMPLIANCE-AWARE-LIGHT-MOTION（P1 新增）**：轻量化⇒柔度/振动；辨识连杆/关节/夹爪主导模态，把柔度并入 `f_track`，用输入整形（ZV/ZVD）+ jerk 受限 prosody + TO 振动惩罚抑制残余振动；顺带降力矩/发热（喂 IP-48）。物理拓扑优化工具/夹爪仅作 **P2 规则待定顾问项（A39）**。
- 「**结构优化（规划侧）**」→ **IP-52 MSS-PLAN-STRUCTURE（P1 新增，重构 IP-49）**：用 MDL/描述长度惩罚技能图复杂度，合并串行原语为复合技能句柄，剪掉结构冗余节点/边；在 E_score 中显式加结构复杂度项，步数与规划算力双降。
- **合并（减少接口 = 轻量化纲领）**：IP-48+IP-25+IP-45 → **RESOURCE-KERNEL**；IP-49+IP-39 → **PLAN-COMPILER**；IP-50+IP-35 → **VERIFIED-MOTION-STACK**（IP-33 CBF 保持独立安全层，不并入）。
- **修剪登记**：IP-42 跨本体 → P2（单 G1 平台，载荷路径不承重）；IP-44 三阶段课程 → P2（保留 LoRA+RARA 最小适配）；IP-46 μ/全形式证书 → 仅保留低层解析证书 + 资源 SLO；IP-26 五轴增广 → P1（数据仍是泛化承重项）。
- **升级**：IP-36 语义图增「物体承重/抓取包络结构」；IP-43 prosody 增「振动抑制模式」；IP-25 SLO 增「结构预算」；IP-38 恢复增「储备结构再扩张」；IP-24 并入 PLAN-COMPILER 的失败记忆。

## 3. 形式化直觉（严格版见产物区 §3）

**定义 29（交付结构图）**：`G=(V,E)`，节点含感知 token、VLM 层、action expert 层、去噪步、TO 迭代、技能节点；每节点代价向量 `c(v)=(FLOPs, bytes, latency, thermal)`；结构决策 `z_v∈{0,1}`。

**定义 30（动作载荷与载荷路径）**：`L(v;σ)=E_{o~D_σ}[‖π(o)−π_{¬v}(o)‖_1 / ‖π(o)‖_1]`（干预移除 v 后动作改变量，F69 的 Δa 的期望版）；尾部载荷 `L*_CVaR(v)=CVaR_α[L(v;σ)]`。三分结构集：`承重 P={v:L*≥ε}`、`储备 R={v:L_nom<ε≤L*}`、`寄生 Q={v:L*<ε}`。

**定义 31（任务刚度 / 干扰柔度 / 结构效率）**：`K(v)=L(v)`（对任务相关干预的响应）；`C_nui=E[‖π(o+δ)−π(o)‖/‖δ‖]`（对干扰的敏感，接 IP-46 Lipschitz）；`η_struct=Σ_v K(v) / (Σ_v c(v)z_v + λ C_nui)`。**结构优化 = 最大化任务刚度、最小化寄生代价与干扰柔度。**

**定义 32（多工况鲁棒结构优化，SIMP 类比）**：
`min_{z∈[0,1]^n} E_σ[L_task(π_z)] + αΣ c(v)z_v + βΣ(1−z_v)L*_CVaR(v)`
`s.t. Σ c(v)z_v≤B_phys; z_v=1 (v∈P); z_v=0 (v∈Q); z_v∈[z_min,1] (v∈R)`；用 `z^p (p>1)` 惩罚推向 0/1、2×2 密度滤波保持空间连续（F77），再投影 + 蒸馏（F73）。

**定义 33（最小充分结构 MSS）**：`G*=argmin_{G'⊆G} [DL(G') + λ·Risk(G')]  s.t. E_score(G')≥(1−ε)E_score(G)`（全场景桶）；`DL` 为技能图描述长度（MDL）。

**定义 34（轻量化比与结构效率）**：`ρ=C_phys(G*)/C_phys(G)`，`η=ΔE_score/(1−ρ)`；目标 `ρ≤0.5` 且**尾部**成功率跌 ≤3%（不是名义）。

**定义 35（结构-预算双层协同）**：外层离线选结构 z（E73/E74），内层每步选动态计算 `k_t=(token 比例, V, A, D, TO 迭代)`，`k_t=argmax reactivity s.t. 预测时延≤L_budget(state) ∧ 热率≤预算 ∧ 预测|Δa|≤ε`。**内层动态结构 = v17 静态旋钮的替代与升级。**

## 4. 关键决断

1. **载荷以动作为准**：语义显著 ≠ 动作承重（F67）；剪枝判据必须过 action-decode/Δa（F69）。
2. **多工况而非名义**：按 F75 的时变多载荷教训，对 5 场景做 CVaR 尾部载荷；只剪「名义 + 尾部都不承重」的结构。
3. **三分结构集 + 储备可再扩张**：承重/储备/寄生，储备结构在 OOD 时一拍内恢复，避免长尾灾难。
4. **内部动态轻量化**：token 骨架/早退/去噪/TO 迭代运行期可调，正面解决 v17 静态旋钮缺陷。
5. **轻量化与柔顺共设计**：物理轻量化的代价是振动，必须输入整形 + 柔度感知 TO，否则省下的热换成精度的债。
6. **对纲领自身修剪**：合并 3 组接口、降级 2 项非承重 IP；每轮新增 P0 ≤1，结构复杂度有上界。

## 5. 本轮最大风险（一句话）

**结构优化最危险的失败不是「剪得不够」，而是「把只在长尾工况承重的载荷路径当寄生质量剪掉」——名义成功率漂亮、5 类泛化场景却灾难失效；因此必须以多工况 CVaR 载荷 + 储备结构可再扩张 + E73–E78 六重守门（任一失败即回退动态轻量化单线、保结构不变），否则 v18 只会得到一艘更轻但会断的桥。**

# 第 41 轮产物 · 创新点清单 v18：载荷路径结构优化 × 轻量化结构 × 最小充分规划（结构-资源共设计，四层架构 v6）

> 承接 v17（第 40 轮：热预算治理 / 步数感知规划 / 学习-TO 混合轨迹，Δ 资源平面）。本轮灵感词「结构优化 / 轻量化结构」经联网核实（口径 2026-11-10）后，把 v17 的 **Δ 资源平面**升级为 **ΔΣ（结构-资源）共设计面**：外层离线优化「计算结构」（哪些 token/层/去噪步/TO 迭代/技能节点真正承重），内层运行期调度「动态计算」（每步按预算伸缩），二者共享同一本热/时延/步数/精度账。新增 **IP-51（P0，载荷路径轻量化）/ IP-52（P1，最小充分规划）/ IP-53（P1，柔顺感知轻运动）**；并把 v17 的 3 组接口合并、2 项非承重 IP 降级——**用同一套结构优化方法修剪研究纲领自身**。主轴从「单位物理成本的得分效率最大化」进一步收紧为「**只保留载荷路径上的结构，且轻量化必须与柔顺/精度共设计**」。

## 0. 结论

- **ΔΣ 共设计面（本轮总纲）**：`Ledger ∪ Structure`。v17 的 H_gpu/Ĥ_motor/S_used/L_p99 账本保留；新增结构账本 `z`（三分结构集：承重/储备/寄生）与结构效率 `η_struct`。**先问结构是否承重，再问旋钮怎么调。**
- **IP-51 LOAD-PATH-LIGHTVLA（P0 新增）**：动作载荷剖析（per token/layer/camera/denoise/TO iter）→ 多工况鲁棒结构优化（SIMP 连续门控 + 因果重要性 + CVaR 尾部载荷）→ token 骨架（2×2 半结构化 + action-decode 双层重要性）+ 动态 V/A/D 早退（Δa 判据）+ 蒸馏。**内部动态轻量化，正面解决 v17「metadata 旋钮半静态化」缺陷。**
- **IP-52 MSS-PLAN-STRUCTURE（P1 新增，重构 IP-49）**：最小充分技能图——MDL/描述长度惩罚 + 复合技能句柄合并 + 结构冗余节点/边剪除；E_score 显式加结构复杂度项，步数与规划算力双降。
- **IP-53 COMPLIANCE-AWARE-LIGHT-MOTION（P1 新增）**：轻量化⇒柔度/振动；辨识主导模态，柔度并入 `f_track`，输入整形（ZV/ZVD）+ jerk 受限 prosody + TO 振动惩罚；顺带降力矩/发热（喂 IP-48）。物理拓扑优化工具仅 P2 顾问（A39 规则待定）。

## 1. 事实卡（新增 F67–F79，检索日期 2026-11-10）

- **F67（VLA-Pruner，arXiv:2511.16449，v5 2026-05-26）**：VLM 通用 token 剪枝按语义显著性选 token，会偏好语义线索、丢弃 action generation 关键信息，显著损害 VLA；作者提出**双层重要性**：vision-language prefill 注意力（语义级）+ action decode 注意力经时序平滑（动作级），并在给定预算下保留紧凑 token 集。**对本轮的直接含义：不能把 VLM 剪枝直接搬来；载荷必须定义在动作空间。**
- **F68（Decoupled Early Exits，arXiv:2609.29382，2026-09-24）**：将 VLM backbone 深度 V、action expert 深度 A、去噪步数 D 暴露为三个**可联合配置**的计算轴；在 backbone 与 action expert 中间深度挂轻量 Exit Transformer，蒸馏最后一层；KV cache 合成允许 action expert 比 backbone 退得更深；最优预算**任务相关**。SmolVLA/π0.5、LIBERO/Meta-World：延迟 −79.2%、FLOPs −31.8%、平均成功率 +5.6%；每个 exit 仅增 2.1%/4.1% 参数。**含义：结构优化必须 task/scene-conditioned，且可增量挂载、无需重训原策略。**
- **F69（A1，arXiv:2604.05672，2026-04-07）**：训练无关的自适应早退，判据是相邻层 action chunk 的差异 Δa（低于阈值 η_i 即退出）；提出 Inter-Layer Truncated Flow Matching 加速早退推理；LIBERO 推理时间 37.9s→10.5s（−72.3%），成功率 92.6%→96.4%，最多去掉 76.6% 层计算，LIBERO 96.6%、LIBERO-Plus 75.3%。核心原则：**spend compute only when it changes the action**。**含义：Δa 是本轮「动作载荷」最直接的可观测代理，且可推理期动态。**
- **F70（MoLe-VLA，AAAI 2026 / arXiv:2503.20384）**：Mixture-of-Layers 动态跳层，受 Shallow Brain Hypothesis 启发；说明动态深度在 VLA 上可行。
- **F71（SparseVLM，ICML 2025，PMLR 267:74840–74857）**：视觉 token 稀疏化；LLaVA 上 FLOPs −54%、CUDA 时间 −37%、精度保持 97%。
- **F72（GRIP-VLM，arXiv:2605.13375，2026-05-13）**：把 token 剪枝建模为 MDP，用 GRPO 直接探索离散选择空间（避免连续松弛陷入次优），预算感知、免重训，等精度下最多 15% 推理加速。
- **F73（C-SWAP，arXiv:2510.18636，BMVC 2025）**：可解释性/因果感知的一次性结构化剪枝，利用预测-结构的 cause-effect 关系渐进剪枝，无需微调，在 CNN/ViT 上取得较好折中。
- **F74（组件感知剪枝，arXiv:2504.13296，IFAC J3C 2025）**：扩展参数依赖图，隔离组件与组件间流，避免在多组件网络中剪断大参数组、破坏功能完整性。
- **F75（多构件机械臂拓扑优化，Struct Multidisc Optim 68:188, 2025，DOI 10.1007/s00158-025-04129-1）**：BESO 框架在**时变载荷、多工况**下最小化平均柔度，计入自重与惯性载荷，考虑串联臂的时变加速度；2D 单臂、3D 双臂面内旋转、3D 三臂空间运动三例；**运动策略与行程时间会改变最优拓扑**。**含义：结构优化必须多工况 + 结构-运动共设计，不能按单一名义工况。**
- **F76（腿部结构拓扑优化，arXiv:2507.16335，2025-07-22）**：SIMP 变密度法 + 结构再设计 + ANSYS 静力/模态验证；股骨减重 19.45%、整腿减重 7.92%，刚度/模态仍满足。**含义：轻量化比 ρ 的合理量级在 0.8–0.9（部件）/更低（整机），且必须过刚度/模态门。**
- **F77（QuietPrune，CVPR 2026）**：query-guided 早期 token 剪枝，用轻量 text-to-vision adapter 将 query 投影为 [Q-CLS]，2×2 半结构化分组、组级相关性剪枝、剪后聚合保留上下文；prefill 延迟最多 −19.0%，精度优于晚期剪枝。**含义：2×2 半结构化分组可作为 token 骨架的空间滤波单元。**
- **F78（HiPrune，ACL 2026 Findings）**：层级注意力、免训练 token 剪枝；保留 anchor/buffer/register token，中层偏 object-centric、深层偏全局。**含义：token 骨架应保留少量锚点/缓冲/寄存器 token，不能只留高分块。**
- **F79（缺口与诚实记录）**：上述工作分别优化 token / 层深 / 去噪 / 剪枝 / 机械结构，但**无人把感知 token、backbone 深度、action expert、去噪步数、TO 迭代、技能图放进同一物理预算下联合做结构优化**；无人以**动作干预载荷**作为闭环 VLA 的剪枝准则；无人用内部动态结构绕开官方 metadata 静态旋钮（F60）。**A39**：赛题只收 `PolicyService`，硬件改造合规性未知 → 物理结构优化只作 P2 顾问，不作得分依赖。**A40–A43**：动作载荷干预可重复性 / G1 结构模态 / 剪枝模型 serving 约束 / 步骤分公式均未核实。

### 3.1 用结构优化修剪研究纲领自身（v17 → v18）

### 3.2 IP-51 LOAD-PATH-LIGHTVLA（载荷路径轻量化，完整设计）

**IP 卡片（六字段）**：
- **动机**：F67 证明 VLM 式语义剪枝会剪断动作信息；F69 证明「只在改变动作时算」可行；F68 证明 V/A/D 三轴可任务相关配置；F73/F74 给出因果/组件感知剪枝工具；v17 的 `obs_keys/resize/T_a/control_space` 锁在 metadata（F60），扰动场景无法动态。**把静态旋钮换成内部动态结构，是同时省算力、省热、提反应性的唯一干净路径。**
- **与现有方案差异**：现有 VLA 加速多是**单轴**（只剪 token，或只早退，或只减去噪）；本项做**联合结构优化**，且载荷判据是**动作干预**而非语义显著性，并引入**多工况 CVaR 尾部载荷 + 三分结构集（承重/储备/寄生）**。文献中未见「储备结构可再扩张」的 VLA 剪枝。
- **技术可行性**：载荷剖析只需对已有策略做干预前向（token drop/merge、层 bypass、去噪步删、TO 迭代截断），无需重训；早退可用 F69 的 Δa 判据；token 骨架用 F77 的 2×2 分组 + F67 的双层重要性；蒸馏用原模型作教师（F68 的 exit 只增 2–4% 参数）；官方接口零改造。
- **所需资源**：算力=1×24GB GPU 做剖析与蒸馏（约 2–3 GPU-days）；数据=仿真/LIBERO 初始化 + 自采 32 任务×5 场景（E73），无需挑战赛私有数据；接口=F60 的 `PolicyService`，模型内部改造。
- **落地步骤**：① E73 载荷剖析（3.2.1）；② 定 ε、z_min、CVaR_α，划三分结构集；③ SIMP 类连续门控 + 蒸馏（3.2.2）；④ token 骨架（3.2.3）；⑤ 动态 V/A/D 与 Δa 早退（3.2.4）；⑥ 接入 RESOURCE-KERNEL；⑦ E74/E75 验收。
- **风险**：尾部载荷估计偏差（→ 多工况 bootstrap + 保守 ε + 储备结构）；动作载荷测量噪声（→ 同观测多次采样、方差入 CVaR）；蒸馏漂移（→ 逐层 KL + 尾部场景回放）；储备再扩张慢（→ 预留低秩旁路，一拍内切换）；**A42 剪枝模型是否满足官方 serving 约束未知**。

**3.2.1 动作载荷剖析协议（E73 的核心）**：
```
输入：已训练策略 π、场景桶 Σ={5 泛化轴}×{任务阶段}、干预算子族 𝕀
对每个子结构 v（逐 token 组 / 逐层 / 每个去噪步 / TO 迭代上限 / 每路相机）：
  对每个 σ∈Σ，采样 M 个观测 o：
    a      = π(o)
    a_{¬v} = π_{without(v)}(o)          # token 丢弃/合并、层 bypass、步删除
    L(v;σ) += ‖a−a_{¬v}‖₁ / max(‖a‖₁, δ)
  L_nom(v) = mean_σ L(v;σ)
  L_cvar(v)= CVaR_0.1({L(v;σ)})           # 尾部：最差 10% 场景桶均值
  置信区间：对 (σ,o) 做 bootstrap，若 CI 上界<ε 才可判寄生
输出：三分集 P={L_cvar≥ε}, R={L_nom<ε≤L_cvar}, Q={L_cvar<ε}（且 CI 上界<ε）
```
**关键细节**：`a` 是 action chunk（T_a 步）而非单步；不同 T_a 下载荷要归一化；token 干预按 2×2 组（F77）而非单 token（避免破坏位置编码）；层干预用「旁路 + 缓存合成」近似 F68；**语义显著性只作辅助先验，不作判据**（F67）。

**3.2.2 多工况鲁棒结构优化（SIMP 类比）**：
```
min_{z∈[0,1]^n}  E_σ[L_task(π_z)] + α·Σ_v c(v)z_v + β·Σ_v (1−z_v)·L*_CVaR(v)
s.t.  Σ_v c(v)z_v ≤ B_phys
      z_v = 1  ∀v∈P          # 承重结构硬保留
      z_v = 0  ∀v∈Q          # 寄生结构硬剪除（仅在 CI 支持时）
      z_v ∈ [z_min,1] ∀v∈R   # 储备：可低精度休眠
      z ← Filter_2x2(z)      # 密度滤波：相邻 2×2 token/相邻层一致，防 checkerboard
      z ← z^p (p>1)          # SIMP 惩罚，推向 0/1
求解：投影梯度/ADMM + 每轮短蒸馏；最后 hard projection + 教师蒸馏校准
```
**与 SIMP 的对应**：`z_v` = 单元密度，`c(v)` = 体积，`L_task` = 柔度（这里换成任务损失），`z^p` = 惩罚，`Filter` = 密度滤波。区别：机械 SIMP 的载荷是力，我们的载荷是**工况相关的动作敏感度**，因此多一项 CVaR 尾部惩罚与三分集硬约束。

**3.2.3 Token 骨架（感知侧轻量化）**：
- **双层重要性**（F67）：`s_v = λ_sem·A_prefill(v) + λ_act·smooth(A_decode(v))`；动作项权重高于语义项（E73 扫 λ）。
- **2×2 半结构化**（F77）：以 2×2 组为剪枝单元，保留位置连续性；组内聚合被剪 token（避免信息硬丢）。
- **锚点保留**（F78）：保留 CLS/register/少量 buffer token；腕部相机在「抓取/插入」相位提升保留率，转移相位降低。
- **动态比例**：`r_t = clip(r0 + κ·(budget_slack), r_min, r_max)`，由 RESOURCE-KERNEL 的 state 驱动；**运行期可变，不受 metadata 限制**。

**3.2.4 动态 V/A/D 与 Δa 早退（推理侧轻量化）**：
```
每层 i（backbone 或 action expert）：
  计算当前 action chunk a_i（用 Exit Transformer 蒸馏头，F68）
  若 ‖a_i − a_{i−1}‖ / max(‖a_{i−1}‖,δ) < ε_a(i, task)：
      exit  # 「计算不再改变动作」
  否则继续
去噪步 D：热启动 + 相邻步 action 差 < ε_D 即停（F69 Inter-Layer Truncated Flow Matching 思路）
TO 迭代：deadline 或 Δx 收敛即停（IP-50v2）
```
阈值 `ε_a(i, task)` 由 E73 在验证集上按「动作差-成功率」曲线标定；**高精度任务（放置/插入）自动提高阈值严格度**（任务相关，F68）。

**正确性论证**：
- **P51（载荷保留的得分界）**：若 `v∈Q` 满足 `L*_CVaR(v)<ε`，则对任意 σ 的动作改变 ≤ε；在任务得分对动作 1-Lipschitz 的假设下，剪除 v 的得分下降 ≤ε。**注意这是条件性命题，依赖 Lipschitz 常数与 ε 标定（A40）。**
- **P52（轻量化-资源单调）**：按定义 `ρ↓ ⇒ Σc(v)z_v↓`，故 FLOPs/latency/thermal 不增；RESOURCE-KERNEL 的可行反应性集单调扩大。
- **P53（储备安全）**：储备集 R 以低精度旁路保留；当 OOD 检测或 `|Δa|>τ` 触发再扩张时，可在**一个 chunk 窗口**内恢复全结构动作；尾部失败率 ≤ P(检测漏报) + 全结构基线。
- **P54（动态早退不劣于静态）**：静态剪枝是 `z` 固定、`k_t` 恒定的特例；动态调度在每步只在预测 `|Δa|≤ε` 时降算力，故其动作误差不超过静态同预算方案（在阈值标定准确时）。

**复杂度**：剖析离线 O(|V|·|Σ|·M) 次前向；SIMP 优化 O(iter·|V|)；运行期 token 骨架 O(N_token)，早退额外参数 ≤4%（F68），调度 O(1)。

### 3.3 IP-52 MSS-PLAN-STRUCTURE（最小充分技能图，完整设计）

**IP 卡片（六字段）**：
- **动机**：F59 排序含步骤分；v17 的 E_score 只看步数 N，不看**计划结构本身**的复杂度；冗余节点/边、重复技能、可合并的串行原语都会增加执行步数与规划时延。结构工程里，去掉非承重杆件不会降低承载力，只会减重；技能图同理。
- **与现有方案差异**：SayCan/GAVEL 优化可行性/可靠性，不显式惩罚计划结构复杂度；本项用 **MDL 描述长度** + 复合技能句柄合并 + 结构冗余剪除，把「计划的最小充分结构」作为一等目标。
- **技术可行性**：技能集 ≤O(100)，图世界模型（IP-36 关系库）可枚举候选；MDL 计算 O(|V|+|E|)；复合句柄是宏动作，执行时展开，不增加底层技能。
- **所需资源**：p_s 先验（E70 自采/开源）、失败记忆、图世界模型；算力本地小 LLM/图搜索，<50ms。
- **落地步骤**：① 在图世界模型上建技能图；② 计算 DL 与风险；③ beam 搜索含复杂度项；④ 复合句柄挖掘（频繁串行子图 → 宏）；⑤ E76 验收。
- **风险**：MDL 权重过大 → 计划过简、成功率降（→ E_score 硬约束 + 尾部场景）；复合句柄过拟合训练任务（→ 只合并高频且跨场景稳定的子图）；图世界模型误差（→ 粗粒度关系，细状态交 IP-50v2）。

**符号表**：`π=(Vπ,Eπ)` 技能图；`DL(π)=Σ_v −log p(s_v)+Σ_e −log p(e)`；`Cost_struct(π)=DL(π)/DL_max`；`Risk(π)=1−Π(1−q_s)`；`λ_c` 结构复杂度权重；复合句柄 `h=(s_1∘…∘s_k)`。

**算法**：
```
输入：指令 l、图世界模型 W、先验 p_s、失败记忆 M_f、场景 σ、预算 knobs
1. 从 l 与 W 生成候选技能图（W 能推的边不调 LLM，GAVEL 原则）
2. 挖掘复合句柄：统计跨任务高频串行子图 (s_1∘…∘s_k)，k≤4，支持度≥θ_h
3. beam search（beam≤16）：
   f(π) = −[ Π_s p_s(s|σ)·g(N_π) − λ·Risk(π) − λ_c·Cost_struct(π) ]
   其中 N_π 用复合句柄展开后的步数；Cost_struct 用 MDL 归一化
   硬约束：E_score(π) ≥ (1−ε_mss)·E_score(π_full)（全场景桶）
4. 结构冗余剪除：若删除节点/边 v 后 E_score 不降且 DL 降，则删（迭代至不动点）
5. 输出 Plan Compiler IR：[(skill|handle, cert_req, budget_req, prosody_hint)]
执行时：复合句柄展开；失败→M_f 查表→策略升级（不原地重试）
```
**正确性论证**：
- **P55（MSS 可行性与不劣）**：全计划 π_full 在搜索空间内，故存在可行解；复杂度项 λ_c≥0 只会把搜索推向更短描述，硬约束保证 E_score 不降超过 ε_mss；因此步数/规划算力不增（在启发式可采纳时）。
- **P56（复合句柄摊销）**：若子图跨任务支持度≥θ_h 且成功率稳定，则展开后的执行步数不变、规划搜索空间缩小；规划时延下降，步数不增。

### 3.4 IP-53 COMPLIANCE-AWARE-LIGHT-MOTION（柔顺感知轻运动，完整设计）

**IP 卡片（六字段）**：
- **动机**：轻量化结构的物理代价是柔度↑、模态频率↓、残余振动↑（F75/F76 都要求轻量化后仍过刚度/模态门）；G1 采用低惯量高速内转子 PMSM 与较轻连杆（F62 旁证），在高加速度取放/交接时更易激发结构振动，直接吃掉末端精度（v17 假说的 <30% 瓶颈）。**轻量化不只发生在网络里，也发生在机器人本体里；控制必须顺应它。**
- **与现有方案差异**：v17 的 TO 与 `f_track` 默认刚体；本项把**连杆/关节/夹爪柔度与主导模态**显式并入跟踪模型，并用输入整形（ZV/ZVD）+ jerk 受限 prosody + TO 振动惩罚三层抑制；不修改硬件，只改策略与参考轨迹。文献中轻量化机械臂的振动抑制与 VLA/TO/热预算尚未打通。
- **技术可行性**：主导模态可由 E77 扫频/脉冲激励辨识（真机或 MuJoCo）；ZV/ZVD 是成熟开环整形器，计算 O(1)；柔度可建模为二阶模态叠加，并入 `f_track`；prosody 已有流式执行器（IP-43）。
- **所需资源**：E77 辨识 ~30–60min 真机激励；MuJoCo 模型（A17）；无额外硬件。
- **落地步骤**：① E77 辨识 ω_i, ζ_i 与载荷依赖；② 柔度二阶模型并入 f_track；③ ZVD 整形器 + 多模态鲁棒版；④ TO 加 `∫‖δ‖²dt + settling_time`；⑤ IP-43 增振动抑制 prosody；⑥ E71 精度复测。
- **风险**：模态随姿态/负载漂移（→ 多模态鲁棒整形 + 载荷估计 + 保守带宽）；辨识噪声（→ 多次激励/置信区间）；过度整形 → 动作变慢、步数升（→ 与 E_score 联合调权）；**A41 G1 模态无公开数据**。

**符号表**：`ω_i, ζ_i` 第 i 阶模态；`δ(t)` 柔度位移；`f_track(x,u)=f_rigid+Σ_i B_i δ_i`；`s(t)` 整形脉冲序列；`w_V, w_S` 振动/整定权重。

**算法**：
```
1. 辨识：脉冲/扫频激励 → 拟合 Σ_i (ω_i, ζ_i, B_i)，并按负载分桶
2. 参考整形：对 IP-50v2 输出的参考轨迹 r(t) 做 ZVD 卷积
   s(t)=Σ_j A_j δ(t−t_j)，使 Σ A_j e^{−ζω t_j} e^{iω_d t_j}=0（零残余振动）
   多模态：对每个 ω_i 同时满足；不确定时用 SI/ZV 鲁棒版放宽
3. TO 目标追加：+ w_V·∫‖δ(t)‖²dt + w_S·T_settle
   约束：整形后轨迹的峰值速度/加速度不超原约束；deadline 不变
4. prosody 映射：高振动段 → 平滑/低 jerk 模式；转移段 → 快速模式
5. 输出：整形后的 T_a 步参考（官方 joint/ee 目标），CBF 仍兜底
```
**P2 物理顾问项（规则待定，A39）**：用 F75/F76 的 BESO/SIMP 对 3D 打印夹爪指/工具做拓扑优化，目标 `<300g`、刚度/模态不降、抓取包络不变；仅在赛事明确允许附件时启用，**否则只作为「不改硬件也能获益」的 IP-53 软件版**。

**正确性论证**：
- **P57（模态整形）**：对线性模态，ZVD 在模型精确时零残余振动；模型误差有界时残余 ∝ 误差，鲁棒整形器把灵敏度降到一阶；多模态叠加时逐模态满足。
- **P58（精度-热双赢条件）**：整形与 jerk 限制降低高频力矩分量 ⇒ `∫τ²dt` 降（喂 IP-48）且末端残余振动降（喂成功率）；代价是段时长增加，需 E71 验证「精度增益 > 步数代价」。

### 3.6 训练/服务伪代码（v18 增量版）

```python
# ===== 离线：动作载荷剖析（E73，IP-51 依赖）=====
def profile_action_load(policy, scenarios, eps, alpha=0.1):
    load = {}
    for v in substructures(policy):                 # token 组/层/去噪步/TO 迭代/相机
        per_sigma = []
        for sigma in scenarios:                     # 5 泛化轴 × 任务阶段
            vals = []
            for o in sampler(sigma, M=64):
                a = policy(o)
                a_wo = policy.without(v)(o)
                vals.append(norm1(a - a_wo) / max(norm1(a), 1e-6))
            per_sigma.append(mean(vals))
        load[v] = dict(nom=mean(per_sigma),
                       cvar=cvar(per_sigma, alpha),
                       ci=bootstrap_ci(per_sigma))
    P = {v for v in load if load[v]["cvar"] >= eps}
    R = {v for v in load if load[v]["nom"] < eps <= load[v]["cvar"]}
    Q = {v for v in load if load[v]["cvar"] < eps and load[v]["ci"][1] < eps}
    return load, P, R, Q

# ===== 离线：多工况鲁棒结构优化 + 蒸馏（E74，IP-51）=====
def optimize_structure(policy, load, P, R, Q, budget, p=2.0, iters=200):
    z = init_gates(P=P, R=R, Q=Q)
    for _ in range(iters):
        z = filter_2x2(z)                           # 空间/层连续
        z = project(z, P, R, Q, budget)             # 硬约束
        loss = task_loss(policy.with_gates(z)) \
             + alpha * phys_cost(z) \
             + beta * sum((1 - z[v]) * load[v]["cvar"] for v in load)
        z = z - lr * grad(loss, z)                  # z^p 惩罚由参数化实现
    z_hard = (z > 0.5).float()
    student = distill(teacher=policy, structure=z_hard,
                      loss=layerwise_kl + action_kl + tail_replay)
    return student, z_hard

# ===== 运行期：ΔΣ 双层调度 + 动态轻量执行 =====
def act_v18(obs, state, kernel):
    ledger = kernel.update(H_gpu=telemetry(), H_motor=motor_heat_proxy(state.q_hist),
                           S_used=state.steps, L=state.latency_ewma,
                           structure=state.z)       # 四账本
    # 1. 内层动态计算预算（替代 v17 静态旋钮）
    k = kernel.schedule(ledger, state.task_phase,
                        k_max=dict(token_ratio=1.0, V=state.V_max,
                                   A=state.A_max, D=state.D_max, to_iters=8))
    # 2. 感知：token 骨架（运行期可变，不受 metadata 限制）
    tokens = dual_level_select(obs, W=state.W,
                               ratio=k.token_ratio,
                               groups="2x2", keep_anchors=True)
    # 3. 规划（resET 后一次 / 失败驱动软重规划）
    if state.need_plan:
        plan = plan_compiler(obs.language, state.semantic_map, state.p_s,
                             state.W, state.M_f, scenario=state.sigma,
                             budget=k, mss=state.use_mss, lam_c=state.lam_c)
        state.plan = plan
    # 4. 运动：VLA 热启动 + TO 精修 + 柔度/整形 + MuJoCo 门
    if state.need_refine:
        warm = stream_policy_head(state.plan.skill, tokens,
                                  V=k.V, A=k.A, D=k.D, eps_a=state.eps_a)
        refined = verified_motion(task=midlevel(state.waypoints, budget=k),
                                  warm=warm, f_track=state.f_track,
                                  compliance=state.compliance,
                                  shaper=state.shaper,
                                  to_iters=k.to_iters)
        state.traj = refined if refined is not None else warm   # 超时/门失败→降级
    # 5. 流式执行 + CBF 兜底
    chunk = state.traj.next_chunk(kernel.T_a_eff())
    if not guard.cbf_check(chunk):
        chunk = resample_or_fallback(state, r=2)
    # 6. 失败/OOD → 储备结构再扩张 + 失败记忆
    if failure_monitor(obs) > TAU_FAIL or ood_score(obs) > TAU_OOD:
        state.expand_reserve()                      # 储备结构一拍内恢复
        state.M_f.log(state.plan.skill, state.fail_sig)
        state.need_plan = True
    return adapt(chunk, control_space=state.control_space)
```

**降级机制 v4（优先序保底）**：

## 6. 清单迭代规则（继承 27–51 + 本轮新增 52–55）

- 继承规则 27–51（通道诚实/映射验证/SLO/fail-safe/灵感-现实校验/单模型合规/步骤分双解释/稠密监督/方法论遗产/元数据重照亮/语言口径分离/摊销/验证器分级/灵感词落地/层级联合规划/跨本体/流式韵律/渐进蒸馏/服务化/证书化/组合代数/热预算/期望得分/学习-TO/修剪优先）。
- **52（新增）：动作载荷路径原则**——任何子结构（token/层/去噪步/TO 迭代/技能节点）的去留，必须以其**动作干预载荷** `L(v;σ)` 与尾部 CVaR 为依据；语义显著性只作先验，不作判据（F67）。结构性简化必须证明「载荷路径未被剪断」。
- **53（新增）：最小充分结构原则**——模型/计划的目标不是最小，而是在**全场景桶 E_score 不降**的前提下最小（MSS）；MDL 描述长度是一等正则项；储备结构必须可再扩张。
- **54（新增）：结构-资源共设计原则**——外层静态结构 z 与内层动态计算 k 必须联合优化；优先用**内部动态结构**（token 骨架/早退/去噪/TO 迭代）替代受 metadata 锁定的外部旋钮；结构预算与热/时延/步数同账本。
- **55（新增）：轻量化-柔顺共设计原则**——任何轻量化（网络或物理）都会改变刚度/模态；必须同时交付柔度/振动补偿（输入整形、jerk 限制、柔度感知 TO），否则轻量化的收益会以精度与步数为代价被收回。

**本轮最大风险一句话**：结构优化最危险的失败不是「剪得不够」，而是「把只在长尾工况承重的载荷路径当寄生质量剪掉」——名义成功率漂亮、5 类泛化场景却灾难失效；必须以多工况 CVaR 载荷 + 储备结构可再扩张 + E73–E78 六重守门，任一失败即回退动态轻量化单线、保结构不变。

**当前最值得押注**：**IP-51 LOAD-PATH-LIGHTVLA**。理由：(a) 它是唯一同时解决 v17「静态旋钮」缺陷与 Δ-Plane 物理成本目标的点，收益确定且可快速证伪（E73 一次剖析 + E74/E75 两轮剪枝即可判定）；(b) 失败模式优雅——最坏退化为「不剪结构、只做动态早退 + token 骨架」，仍不劣于 v17；(c) 它的载荷图会反向喂养 IP-52（技能结构）与 IP-53（承重/柔度结构），是三条线的公共测量基础设施。**上限最高的一注则是 IP-53**：若 G1 的结构振动确实是末端精度瓶颈，输入整形可能是最便宜的一次精度跃升；但它依赖 A41 辨识，确定性低于 IP-51。
