# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配多模态交互消歧」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「放置」×「行为树」）

> R68 的答案是「不确定就**放慢**」（λ_floor），R69 的答案是「不确定就**去问**」（VoI）。但两者都默认了一件在真实系统里经常不成立的事：**动作是可撤回的**——这一步做错，下一步还能改；这次没看清，下次再问。可有一大类动作不是这样：**松手、放下、交给人类、把脚踩下去、把一条结论写进账本**。一旦发生，世界就被改写了：慢放没有意义（你不能「以 0.5 倍速松手」），追问也来不及（信息只能在边界之前获得）。
>
> 本轮两个灵感正好补上这两块：
> - **放置**是「不可逆承诺」的原型：它向世界**写**下一条持久后置条件（杯子立在桌上且稳定、脚掌落在可支撑区域、传感器部署到位、一条前提被接受）。放置不是选一个点，而是选一个**可行域里的稳健区**。
> - **行为树**是「读前提条件来组织可回退行为」的原型：守卫—动作—回退（Sequence/Selector/Parallel），结构上保证没有哪个提交能绕过它的守卫，并让「可逆」有了操作化定义——**存在一条能恢复前置条件的恢复子树**。
>
> 核心命题：**把「放置/承诺」建模为对世界的一次不可逆写，把行为树建模为对这次写的读；安全不是「放慢」，而是「写之前守卫必须新鲜、可行、且存在可执行的恢复子树」。R69 的 aleatoric/epistemic 二分因此获得一条时间轴：在提交边界之前，epistemic 可看可问；越过边界，它就冻结为 aleatoric。** 命名 **ANCHOR-RAS**（Affordance-certified Node-structured Commitment with Hierarchical Override and Recovery）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**这一步一旦落下，我还回得来吗；我该在哪个瞬间放手**」——不确定性不仅是刹车与提问，也是一次不能撤回的落子。

## 0. 直觉与动机

**灵感 1（放置 → 这是一次不可逆写，λ 缩放对离散提交天然失效）**
直觉：R68 的 λ_floor 是连续控制上的标量收缩，它假定「慢一点就更安全」。但对「松手」这个事件，慢没有任何语义：手指张开是一个二值事件，要么夹住、要么放下。R69 的 VoI 也一样：它假定信息动作和任务动作在同一个连续轨迹里，可如果提交已经发生，**再多的信息也换不回原来的状态**。更一般地，凡是「建立持久约束」的动作——放置物体、部署传感器、踩下支撑脚、在对话里接受一个前提、把某物标记为已完成——都在**写世界**，而写是不可逆的。所以 R70 不是再给闭环加一个「更聪明的缩放」，而是承认：**存在一类动作根本不归 λ 和 VoI 管，它们需要一个提交前的守卫结构**。

**灵感 2（放置 → 可放置性是一个集合，安全是「往可行域内部收缩」）**
直觉：新手放杯子会盯着一个理想点；老手会先看桌面支撑面够不够、杯底会不会悬空、离桌沿多远、被人碰一下会不会倒。也就是说，放置的安全量不是「离目标点多近」，而是**在不确定与扰动下还能不能稳定成立**。这把 R68 的「收缩」从动作幅度搬到了**可行域**：不是把动作缩小，而是从一个点 `p*` 收缩到一个稳健集合 `P_ε`，让最坏扰动仍落在可行域内。放置因此天然是一个**最坏情形优化**问题（最大化稳定裕度），而不是一个点估计问题。它也给出一个漂亮的判据：**如果可行域内部已经没有余量，正确的行为不是「轻轻地放」，而是「先别放」**。

**灵感 3（行为树 → 写-读契约：放置写后置条件，守卫读前置条件）**
直觉：放置与行为树其实是一对偶：**放置负责写前置条件，行为树负责读前置条件**。杯子被放下后，「桌上有杯且稳定」成为后续「倒水」「递给用户」这些叶子的前置条件；如果这条后置条件没有被可靠写下，后面的行为树就是建在沙子上。传统行为树的脆弱正在此：它的 condition 节点是手写的、假定了世界如你所愿。本轮要把它升级为**契约行为树（C-BT）**：每个节点带 `(Pre, Post, Inv, Eff)` 契约，提交叶（放置/松手）必须有守卫支配（guard domination），守卫的前提必须来自 R68 的标定感知与 R69 的正交证据。于是安全从「轨迹前缀认证」升级为**结构可静态验证的组合契约**——这也是对 R68「只认证一条前缀」的一个真正模块化。

**灵感 4（行为树 → 「可逆」不是动作的属性，而是 (动作, 状态, 树) 的属性）**
直觉：同一个「松开夹爪」，在桌面上方是可恢复的（掉了还能捡），在悬崖边是不可恢复的（掉了就没了）；同一个「踩下这一步」，有落脚恢复位就是准可逆，悬空就是不可逆。所以 §1 要把承诺代价写成 `κ(a, s, T)` 而不是 `κ(a)`——**可逆性取决于当时是否存在一条恢复子树**。这带来一个可直接工程的结论：与其笼统地害怕不可逆动作，不如**显式维护恢复子树注册表**；当恢复子树不可达时，系统应自动把该动作升级为「不可逆」，从而抬高证据门槛。行为树的 Selector/Fallback 恰好就是恢复子树的自然载体。

**灵感 5（提交边界 → epistemic 在边界处相变，于是出现「最后机会」）**
直觉：R69 把不确定性分成可约的 epistemic 与不可约的 aleatoric，但没给它们时间维。其实同一个 epistemic，在提交前是可问的，越过提交边界后就**冻结**成 aleatoric——你再也不能通过任何允许的动作把它降下来。于是出现一个 R68/R69 都没有的对象：**最后机会价值（last-chance value）**。它不是「现在问值不值」，而是「现在不问，下一秒就永远问不到了，值不值」。这给行为树一个非常自然的语义：**守卫未满足时不允许进入提交叶，系统宁可在提交前的可中断区里等待/求证，也不许「先做后想」**。同时，行为树的高优先级抢占带来一个新危险：在机械臂把物体放到一半时被更高优先级分支打断，会导致掉落——所以必须定义**承诺窗口**（提交临界区不可抢占，或只能安全完成/安全中止）。

**灵感 6（新攻击面 → 结构安全 ≠ 语义正确）**
直觉：行为树能保证「结构上不绕过守卫」，却保证不了「守卫说的就是对的世界」。最危险的失效不是没守卫，而是**守卫被陈旧信息或共模证据满足**：检查时安全、使用时世界已变（TOCTOU），或视觉、力觉、语言三个「独立」证据其实被同一个扰动同时骗过。再加上放置特有的**语义误泛化**（几何上稳定，但把杯柄朝向人、把物体放进禁区、把一个前提解释反），以及「问—等—再问」的活锁。R70 必须同时交付：守卫时效与原子提交、共模证据检测、语义约束、无活锁进展度量。否则行为树只是把一个会犯错的系统包装得更像「有章法」。

## 1. 形式化定义（增量：定义 310–329）

**定义 310（ANCHOR-RAS 总览）** ANCHOR-RAS = (CPT, PAM, C-BT, TSC, SGC, CVL, PIP, RSR, RTT, BTI, RAS-WM§)。四不变式：
(i) 继承 R68 实时流零学习写操作（定义 276-i）与 R69 证据纪律（定义 293-iii）；
(ii) **提交单调性**：任何提交叶执行前，其守卫必须在**当前时刻**通过，且守卫在结构上支配该叶（定义 315）；
(iii) **恢复可行性**：每个提交叶必须有可达恢复子树且成功率 ≥ 1−δ_r，否则被归为不可逆并抬高证据门槛（定义 322–323）；
(iv) **tick 一致性**：控制前缀在整棵树的 tick 内保持 R68 认证不变，提交只允许发生在前缀边界（定义 324）。

**定义 311（承诺原语与承诺代价）** 动作按可逆性分层：𝒜_rev（连续可纠正，恢复代价≈0）、𝒜_qrev（有界恢复代价的准可逆，如重新抓取）、𝒜_irr（不可逆提交，如松手/放置/交接）。承诺代价定义为
κ(a, s, T) = inf_{ρ ∈ Rec_T(s)} E[C(ρ)]，若 Rec_T(s)=∅ 则 κ=∞，
其中 Rec_T(s) 是在状态 s、行为树 T 下能恢复 a 之前置条件的恢复子树集合，C(ρ) 为恢复代价。**可逆性不是动作的固有属性，而是 (a, s, T) 的属性**——这正是行为树与放置的接口。

**定义 312（放置流形 PAM）** 放置动作 a_place = (p, r, t_r)：位姿 p ∈ SE(3)、释放策略 r、释放时刻 t_r。在观测 o 下的可行集
P_feas(o) = { p : support(p,o)=1 ∧ collision_free(p,o)=1 ∧ reachable(p,o)=1 ∧ Sem(p,o)=1 }，
其中 Sem 为语义约束（杯柄朝向、禁区、标签朝上、人可及性）。稳定裕度
s_m(p) = min_{e ∈ ∂SP(p)} dist(proj_CoM(p), e) / √(tr Σ_geo)，
SP 为支撑多边形，Σ_geo 为几何估计协方差。**稳健放置区** P_rob = { p ∈ P_feas : s_m(p) ≥ s_min ∧ clearance(p) ≥ c_min ∧ drop_h(p) ≤ h_max }。放置的可执行判据是 P_rob ≠ ∅，而不是「p* 存在」。

**定义 313（放置即写后置条件：写-读契约）** 世界状态谓词格 (Ψ, ⊑, ∧, ∨)。一次已提交放置写后置条件 ψ ∈ Ψ（如「杯在桌上、直立、s_m ≥ s_min、不越界」），世界 w → w′ ⊨ ψ。行为树中任一读世界状态的守卫，其前置条件 φ 必须满足 **ψ ⊑ φ**（在 R68 的标定不确定包络内蕴含）；不满足则守卫不得放行。这把「放置」和「行为树」统一为**写者-读者**：放置写 ψ，守卫读 φ，安全 = 每次读都被一次已认证的写所蕴含。

**定义 314（契约行为树 C-BT）** C-BT = (N, E, root, BB)。节点 n ∈ N 带契约 (Pre_n, Post_n, Inv_n, Eff_n)，Eff_n = (Δrisk, Δbudget, Δcommit, Δheat)。节点类型：Sequence(∧)、Selector/Fallback(∨)、Parallel(⊤)、ActionLeaf、Guard、**CommitLeaf**、**RecoverySubtree**。tick 返回 {Success, Running, Failure}，节点带记忆（Running 不重复进入已完成子树）。黑板 BB 存信念、证据、承诺账本与预算。

**定义 315（守卫支配提交叶）** 提交叶 c 被守卫支配，当且仅当从 root 到 c 的**每一条**路径都经过某守卫 g，且运行期满足
Pre_g ∧ fresh(g) ∧ (ψ_g ⊑ Pre_c) ∧ Pre_c。
这是控制流图上的**支配（dominator）关系**在行为树上的实例，可静态检查（定义 316/TSC）。

**定义 316（组合契约可靠性）** C-BT 是契约可靠的，若 (a) 每个节点契约在其前置条件下成立；(b) 每个提交叶被新鲜守卫支配；(c) 每个 Selector 的失败回退可终止；(d) 每条恢复子树以 Post 恢复 Pre。则对任意 tick 前缀，根契约 Inv_root 与 Eff_root 的预算约束保持。证明按 tick 归纳（见引理 20）。

**定义 317（提交边界与不确定性相变）** 对提交动作 a，定义提交边界 t†（松手/写入生效时刻）。残差不确定性
U_pre = U_epi(a)（t < t†，可被信息动作降低），U_post = U_epi(a)（t > t†，冻结为 aleatoric，进入 R68 的 λ_floor）。
**相变律**：任何在 t† 之后才执行的交互对残差无因果效力，故其 VoI(t > t†) ≡ 0。因此所有可约部分必须在 t† 之前处置，否则永久并入 U_ale。

**定义 318（承诺价值与最后机会 CVL）** 在提交时刻候选 now 与等待一个信息动作再提交候选 wait 之间：
OV = E_y[ U(commit | o, y) ] − U(commit | o)，LCV = U(commit now) − OV。
提交当且仅当 LCV ≥ c_wait 且 (U_post 的期望后悔 ≤ R_max)；否则在可中断区等待/求证。OV 是**选项价值**，LCV 是**不等待的机会损失**。这把 R69 的「问值不值」升级为「现在不问以后还问不问得到」。

**定义 319（稳健放置投影 PIP）** 面对不确定 δ ∈ Δ（几何、摩擦、漂移），不提交点估计 p*，而提交
p† = argmax_{p ∈ P_rob} min_{δ ∈ Δ} Q_place(p+δ)，
Q_place = s_m − α·ε_geo − β·κ̂ − γ·1[Sem 风险]。
即**往可行域内部收缩到最坏情形最优点**；若 min_{δ} Q_place ≤ 0，则拒绝提交（先别放）。

**定义 320（守卫时效与原子提交 SGC）** 每个守卫有新鲜度时间戳；超过 τ_stale 即失效。检查到提交存在延迟 Δt，世界漂移有界 ‖w(t+Δt)−w(t)‖ ≤ L_d·Δt。提交允许条件为
s_m(p†) > L_d·Δt + ε_toctou ∧ fresh(g) ∧ 原子预留成功。
「原子提交」= 在临界区内重新校验并预留位姿/力，禁止 check 与 commit 之间插入任何会改写相关世界谓词的动作（TOCTOU 消除）。

**定义 321（承诺窗口与可中断性）** 每个提交分为：可抢占的**提交前区**、临界区 [t†−ε_c, t†+ε_c]，以及提交后区。中断语义仅允许「安全完成（finish）」或「安全中止（abort-safe，恢复到 Pre 且不改变 ψ）」；**临界区内禁止任意抢占**。行为树的高优先级分支在临界区只能请求「完成/中止」，不能直接丢弃 Running 子树。

**定义 322（恢复子树与可行性 RSR）** 提交 c 的恢复子树 ρ(c) 带成功下界 π_rec、代价上界 C_rec、时限 t_rec。c 可采纳当且仅当
π_rec ≥ 1−δ_r ∧ E[regret] = κ·P_bad + C_rec·(1−π_rec) ≤ R_max。
若 ρ(c) 不可达（Rec_T=∅，κ=∞），c 升级为**不可逆**，其证据门槛按定义 323 抬高。

**定义 323（承诺分级证据门槛）** 证据充分度 e(o) 复用 R69（ECE + k 个正交源一致）。门槛随承诺代价单调：
τ_rev ≤ τ_qrev ≤ τ_irr，e(o) ≥ τ_κ 才允许提交。
即 **κ 越大，越要求「多源、低 ECE、新鲜」的证据**；对不可恢复动作，接受阈值取最保守档（可退化为「永不提交，改为求助」）。

**定义 324（双速率 tick 与认证前缀 RTT）** 行为树以 f_bt 运行，控制环以 f_ctrl ≫ f_bt 运行。tick 输出 R68 认证的前缀 k（或 mode.a[:k]），在 [t, t+k] 内不再改变契约；提交只允许发生在 tick 边界与前缀边界对齐处。避免「树在 tick 中途改主意」导致的前缀失效与突变。

**定义 325（活跃性与无活锁）** 定义进展测度 μ(节点状态, 预算)。要求每个 Running/等待/求证循环使 μ 严格下降；Selector 的模态切换带滞回带 h（防止两分支翻烧饼）；求证循环总次数受交互预算（R69 定义 293-ii）限制。μ 有下界 ⇒ 有限步终止。

**定义 326（承诺后悔界）** 在守卫通过下提交的错误概率 P_bad ≤ P(ψ 未成立 | 守卫)，期望后悔
E[regret] ≤ κ·P_bad + R_max·P(recovery fail)。
要求 E[regret] ≤ R_max；这给出「何时宁可不提交」的显式判据，也是分级证据门槛 τ_κ 的由来。

**定义 327（BT 审计 BTI / VQAuditor-B）** 节点级审计：守卫是否被共模证据满足、是否陈旧提交、是否过早提交、是否语义违规、是否活锁/翻烧饼、恢复子树是否真的可达。结论回灌 AuditBuf 与恢复子树注册表。

**定义 328（对抗干扰集 AIC-ANCHOR）** ℰ_ANCHOR = ℰ_FLUID × ℰ_commit，其中
ℰ_commit = { 过早提交, TOCTOU 漂移, 共模守卫欺骗, 恢复子树不可达, 语义放置攻击, 活锁/震荡, 条件节点奖励黑客 }。

**定义 329（证书 J_ANCHOR）** J_ANCHOR = (J_FLUID, commit_log_hash, guard_freshness_p99, placement_margin_min, recovery_depth, tree_static_ok, livelock_free, u_pre_u_post_delta, anchor_ver)。
Valid ⇔ Valid(J_FLUID) ∧ tree_static_ok ∧ guard_freshness_p99 ≤ τ_stale ∧ placement_margin_min > 0 ∧ livelock_free。

**定义 330（与 FLUID-RAS 的严格包含）** 当行为树不含任何 CommitLeaf（所有动作 ∈ 𝒜_rev）时，ANCHOR 的守卫与提交逻辑全部旁路，逐指令退化为 FLUID-RAS；当存在提交叶时，ANCHOR 只在提交处**收紧**（更高证据门槛 + 恢复可行性），不放松任何 R68/R69 的安全约束。故 R70 是 R69 在「可逆世界」边界上的严格退化、在不可逆世界上的严格加固。

## 2. 关键算法骨架

```python
# IP-264/265 PAM：放置可行域 + 稳健投影（安全是往内部收缩，不是对准一个点）
def placement_commit_pose(o, delta_ball, kappa_hat):
    feas = feasible_placement_set(o)          # support / collision / reach / Sem
    if not feas: return None                  # 没有可行域 -> 先别放
    best = max(feas, key=lambda p: worst_case(
        lambda d: q_place(p + d, kappa_hat), delta_ball))
    return best if worst_case(lambda d: q_place(best+d, kappa_hat), delta_ball) > 0 else None

# IP-266/267 C-BT：契约节点与守卫支配的提交叶
class CommitLeaf:
    def __init__(self, action, pre, post, recovery):
        self.action, self.pre, self.post, self.recovery = action, pre, post, recovery
    def tick(self, bb):
        if not bb.guard.fresh(self.pre):  return "Failure"   # 陈旧/未满足 -> 不提交
        if not sgc.reserve_and_recheck(self.pre): return "Running"  # 原子校验，等待
        if self.recovery is None or self.recovery.success_lb < 1 - DELTA_R:
            return "Failure"                                   # 不可恢复 -> 抬高门槛或求助
        return self.action.execute()                           # 只有这里才真的“落子”

# IP-268 TSC：守卫支配的静态检查（树上做 dominator 分析）
def static_certify(tree):
    dom = dominators(tree)                     # 标准支配树
    for c in tree.commit_leaves:
        guards = [g for g in dom[c] if g.kind == "Guard"]
        if not any(g.contract.post entails c.pre for g in guards):
            return False                       # 存在绕过守卫的路径
    return acyclic(tree) and fallbacks_terminate(tree) and budget_well_founded(tree)

# IP-270/271 CVL + RSR：最后机会 + 恢复可行性
def should_commit(now_cand, info_actions, recovery, budget):
    if recovery is None or recovery.success_lb < 1 - DELTA_R:
        return False if evidence(now_cand) < TAU_IRR else True
    ov  = expected_utility_after_one_info(info_actions)   # 选项价值
    lcv = utility(now_cand) - ov
    return lcv >= WAIT_COST and expected_regret(now_cand, recovery) <= R_MAX

# IP-263 主闭环（继承 R69，仅在“提交/放置”处插入 ANCHOR 层）
def ANCHOR_RAS_round(M, obs):

    # 1) R69：歧义分解与可选交互（仍在提交边界之前）
    K = 1 if M.fmp.mode_head(z) < TAU_MODE else 4
    samples = M.fmp.sample(o, K)
    U_ale, U_epi, modes, _ = M.aud.decompose(samples, z, M.fmp.mode_head)
    g = (M.mint.choose_interaction(modes, o, M.budget)
         if U_epi > TAU_EPI and not M.fma.slow_fault_suspect() else None)
    if g is not None: U_epi = M.cia.update_belief(modes, M.cia.execute(g))
    # 2) 行为树 tick：为每个候选动作算承诺代价与恢复可行性
    bt = M.cbt.tick_modes(modes, blackboard=M.bb)
    for leaf in bt.frontier:
        leaf.kappa = M.cpt.commit_cost(leaf.action, M.state, M.cbt)   # (a,s,T)
    commit_leaf = bt.selected_commit if bt.has_commit else None
    # 3) 提交前：稳健投影 + 最后机会 + 新鲜/原子/恢复三重门
    if commit_leaf is not None:
        p_dag = M.pam.robust_projection(o, M.uncertainty_ball, commit_leaf.kappa)
        if p_dag is None:

        if not M.rsr.admissible(commit_leaf, M.registry):
            commit_leaf = M.cbt.escalate_to_ask()      # 不可恢复 -> 求助而非硬放
        if not M.cvl.should_commit(commit_leaf, M.info_candidates, M.rsr, M.budget):
            return bt.wait_in_precommit()              # 等一个信息动作，留最后机会
        if not M.sgc.atomic_check_and_reserve(commit_leaf, p_dag, M.staleness):
            return bt.wait_in_precommit()              # 陈旧/TOCTOU -> 不进入临界区
    # 4) 选模态 + R68 认证前缀（提交只在 tick/前缀边界发生）
    mode = select_mode(modes, U_epi, M.lam)
    U_floor = U_ale + (U_epi if g is None else 0.0)
    lam = max(M.efs.risk_scale(...), lam_floor(U_floor))
    k = M.c_ras_wm.certified_prefix(M.ach.propose(x_prime, M.vista.H), ..., wm_preds)
    # 5) 执行：可逆动作用 R69；提交叶进入承诺窗口（临界区不可抢占）
    if commit_leaf is not None and commit_leaf.ready:
        out = M.commit_window.execute(commit_leaf, p_dag, mode.a[:k], lam)
    else:
        out = M.pi_sigma.prefix_dispatch(mode.a[:k]) * lam

    M.bti.submit_async(bt.trace, commit_leaf, p_dag, U_epi, M.registry)
    return out, (U_ale, U_epi), bt.status
```

## 3. 推导

**引理 19（提交边界处的 epistemic→aleatoric 相变）** 设提交边界 t† 后不再允许任何能降低模态身份 M 的观测/交互动作。则对 t > t†，I(M; y | do(a_t)) = 0 对所有可行动作成立，故 VoI ≡ 0，残差 U_epi 必须并入 U_ale 进入 λ_floor。系：**所有可约不确定性的处置必须前移到 t† 之前**；R69 的 VoI 只在 t < t† 有意义，R70 的 CVL 就是在算「是否已到最后一次可处置的 tick」。

**引理 20（守卫支配的组合可靠性）** 若 C-BT 满足定义 316(a)–(d)，则任一执行前缀内，提交叶 c 执行时 `Pre_c` 成立，且写入的 `ψ_c ⊨ Post_c`；因此后续读到该谓词的守卫不会被未认证的写欺骗。证明：对 tick 序列归纳——提交叶仅在新鲜守卫且 `ψ_g ⊑ Pre_c` 时执行（定义 315），恢复子树保持 `Post` 恢复 `Pre`，Selector 失败回退可终止，故归纳步保持 Inv_root。系：**安全从「单条轨迹前缀认证」升级为「树的结构 + 节点契约认证」**，这是 R68 C-RAS-WM 的模块化推广。

**引理 21（稳健投影的 TOCTOU 鲁棒性）** 记世界漂移 Lipschitz 常数 L_d、检查到提交延迟 Δt、几何/摩擦不确定球半径 ε_geo。若 `s_m(p†) > L_d·Δt + ε_toctou` 且 `min_{δ∈Δ} Q_place(p†+δ) > 0`（定义 319–320），则在提交瞬间 ψ 仍成立的概率 ≥ 1−δ_geo。即**把放置点往可行域内部收缩，等价于给「检查-使用」时差买了一份保险**；反之，贴边放置即使检查时安全，也会在 Δt 内失效。

**引理 22（承诺后悔上界与分级门槛）** 在守卫正确率 p_g = P(ψ | 守卫通过) 下，提交的期望后悔
E[regret] ≤ κ·(1−p_g) + C_rec·(1−π_rec) ≤ R_max
给出可分级的证据门槛：对 κ=∞ 的不可恢复动作，必须 p_g → 1（等价 τ_irr 取最保守档），否则 `E[regret] = ∞`，任何有限安全预算都不允许提交。系：**分级门槛不是拍脑袋，而是后悔界的反解**。

**定理 18（ANCHOR 严格包含 FLUID-RAS）** 当 C-BT 无提交叶（所有动作 ∈ 𝒜_rev）时，守卫与提交逻辑旁路，PAM/CVL/SGC/RSR 不改变动作选择，故 ANCHOR 与 FLUID-RAS **逐指令相同**；当存在提交叶时，ANCHOR 仅在提交处施加额外约束（新鲜守卫、`ψ ⊑ Pre`、恢复可行、分级证据、原子预留），不取消 R68/R69 的任何安全约束。因此任意状态期望风险 ≤ FLUID-RAS，安全侧不让步，只在「可逆性」维度加固。

**定理 19（无活锁与承诺迟滞有界）** 在定义 325 的进展测度 μ 严格下降、交互预算有限、Selector 带滞回 h 的条件下，C-BT 在有限 tick 内要么 Success、要么 Failure、要么进入显式的「等待/求助」终止态；模态翻烧饼次数 ≤ (J_span / h) + O(1)，不出现无穷「问—等—再问」。系：**行为树的记忆 + 预算单调性，天然把 R69 的交互死循环排除**。

**定理 20（结构安全可静态验证 + 运行期 O(1) 复核）** TSC 的支配分析对「守卫支配提交叶」是**可靠且完备**的（树上 dominator 唯一），对「回退可终止」「预算良基」亦是可靠检查；运行期只需复核新鲜度与预留（SGC），复杂度 O(1) 每 tick。故静态证书 `tree_static_ok` 一旦生成即可缓存，运行期只支付 O(1) 复核与放置可行性计算。

## 6. 本轮最大风险

**一句话**：ANCHOR-RAS 的安全性完全押在「守卫看到的世界就是提交那一刻的世界」这一前提上——**行为树只能保证结构上没绕过守卫，保证不了守卫本身新鲜且语义正确；一旦放置可行性模型或守卫时效被系统性偏置/共模欺骗，系统会以「结构已认证」的自信执行一次不可撤回的落子，而这种错误既不能靠放慢（λ 对离散提交无效）也不能靠事后追问（提交后 epistemic 已冻结）来补救**——**一个错误的提交，比任何数量的错误动作都更难挽回**。

**次级风险与缓解**：守卫陈旧/TOCTOU（定义 320 + 引理 21 + E304）；不可恢复动作被误当可恢复（定义 311/322 + 分级门槛 + E306）；共模证据欺骗（R69 正交证据纪律 + 定义 327 审计 + E310）；语义放置误泛化（语义约束 Sem + 人类求证 + E309）；行为树活锁/震荡（进展测度 + 滞回 + 定理 19）；`\kappa`/可行性模型本身的标定误差（保守内缩 + 拒绝提交优先于硬放）。

## 2. 形式化定义（要点版）

**定义 310（总览与四不变式）** 提交单调性（提交前守卫必须当前通过且结构支配）；恢复可行性（每提交有可达恢复子树 π_rec ≥ 1−δ_r，否则升级为不可逆）；tick 一致性（控制前缀在 tick 内不变，提交只在前缀边界）；继承 R68 零学习写操作 + R69 证据纪律。

**定义 311（承诺代价 κ(a,s,T)）** 可逆性由「是否存在恢复子树」定义，而非动作固有属性：`κ = inf_{ρ∈Rec_T(s)} E[C(ρ)]`，`Rec_T=∅ ⇒ κ=∞`。同一松手动作在桌面上方与悬崖边具有完全不同的 κ。

**定义 312（放置流形 PAM）** `P_feas = {support ∧ collision_free ∧ reachable ∧ Sem}`；`s_m = min_e dist(proj_CoM, ∂SP)/√trΣ_geo`；`P_rob = {s_m ≥ s_min ∧ clearance ≥ c_min ∧ drop_h ≤ h_max}`。放置可执行 ⇔ `P_rob ≠ ∅`。

**定义 313（写-读契约）** 放置写 ψ；守卫读 φ；仅当 `ψ ⊑ φ`（标定包络内）才放行。放置=写前置条件，行为树=读前置条件；安全=每次读都被已认证的写蕴含。

**定义 314–316（C-BT / 守卫支配 / 组合可靠）** 节点带契约；提交叶被守卫支配 ⇔ root→c 每条路径都过守卫且运行期 `Pre_g ∧ fresh(g) ∧ ψ_g ⊑ Pre_c`；四条件 (a)–(d) 下按 tick 归纳保持根契约。

**定义 317–318（提交相变与 CVL）** t > t† 时任何交互 VoI ≡ 0，epistemic 冻结为 aleatoric；`OV` 为等待一次求证的期望增益，`LCV = U(commit now) − OV`；`LCV ≥ c_wait` 且期望后悔 ≤ R_max 才提交。

**定义 319–321（PIP / SGC / 承诺窗口）** `p† = argmax_{P_rob} min_δ Q_place`，内部无点则拒绝提交；提交要求 `s_m(p†) > L_d·Δt + ε_toctou`、新鲜守卫、原子预留；提交分可抢占前区、临界区（不可任意抢占）、提交后区，临界区只允许安全完成/安全中止。

**定义 322–323（恢复可行性与分级门槛）** `π_rec ≥ 1−δ_r` 且 `E[regret] = κ·P_bad + C_rec·(1−π_rec) ≤ R_max`；证据门槛 `τ_rev ≤ τ_qrev ≤ τ_irr`，κ 越大要求越保守，κ=∞ 时可退化为「永不提交、改为求助」。

**定义 324–327（RTT / 无活锁 / 后悔界 / BTI）** 双速率与提交对齐前缀；进展测度 μ 严格下降 + 滞回 h ⇒ 有限步终止；`E[regret] ≤ κP_bad + R_max P(rec fail)`；节点级审计捕获共模、陈旧、过早、语义违规、活锁与恢复不可达。

**定义 328–330（干扰集 / 证书 / 包含）** `ℰ_ANCHOR = ℰ_FLUID × ℰ_commit`；`J_ANCHOR = (J_FLUID, commit_log_hash, guard_freshness_p99, placement_margin_min, recovery_depth, tree_static_ok, livelock_free, U_pre/post, anchor_ver)`；无提交叶时逐指令退化为 FLUID-RAS。

## 3. 关键算法伪代码

```python
# IP-265/271 PAM + PIP：先有可行域，再往内部收缩；无内点则“先别放”
def robust_placement(o, delta_ball):
    P = feasible_set(o)                      # support/collision/reach/Sem
    if not P: return None
    p = max(P, key=lambda x: min(q_place(x+d) for d in delta_ball))
    return p if min(q_place(p+d) for d in delta_ball) > 0 else None

# IP-266/267 C-BT：守卫支配的提交叶（结构保证 + 运行期三重门）
class CommitLeaf:
    def tick(self, bb):
        if not bb.guard.fresh(self.pre):          return "Failure"   # 陈旧
        if not sgc.atomic_reserve(self.pre):      return "Running"   # 原子校验
        if not rsr.admissible(self):              return "Ask"       # 不可恢复→求助
        return self.action.execute()              # 临界区：真的落子

# IP-268 TSC：支配分析静态证书（离线，运行期只验哈希）
def certify(tree):
    dom = dominators(tree)
    ok  = all(any(g.post_entails(c.pre) for g in dom[c] if g.kind=="Guard")
              for c in tree.commits)
    return ok and acyclic(tree) and fallbacks_terminate(tree) and budget_wf(tree)

# IP-270 CVL：最后机会价值（提交边界前的信息期权）
def should_commit(cand, infos, rec):
    if rec is None: return evidence(cand) >= TAU_IRR
    return (utility(cand) - expected_after_one_info(infos) >= WAIT_COST
            and expected_regret(cand, rec) <= R_MAX)

# IP-269 SGC：新鲜度 + 漂移裕度 + 原子预留（消灭 TOCTOU）
def atomic_commit_ok(p, g, dt):
    return g.fresh() and sm(p) > L_D*dt + EPS_TOCTOU and reserve(p)

# IP-276 主闭环：R69 负责“边界前”，ANCHOR 负责“边界处”
def ANCHOR_RAS_round(M, obs):
    z, o = M.mtm.forward(...); c,U_cal,_ = M.cof.step(...)
    K = 1 if M.fmp.mode_head(z) < TAU_MODE else 4
    U_ale, U_epi, modes, _ = M.aud.decompose(M.fmp.sample(o,K), z, M.fmp.mode_head)
    g = M.mint.choose_interaction(modes,o,M.budget) if U_epi>TAU_EPI else None
    if g: U_epi = M.cia.update_belief(modes, M.cia.execute(g))   # 边界前求证
    bt = M.cbt.tick(modes, M.bb)
    leaf = bt.selected_commit
    if leaf:
        p = M.pam.robust_projection(o, M.ball, leaf.kappa)
        if p is None:                 return bt.fallback_noncommit()
        if not M.rsr.admissible(leaf):return bt.escalate_to_ask()
        if not M.cvl.should_commit(leaf, M.infos, M.rsr):
                                      return bt.wait_in_precommit()
        if not M.sgc.atomic_reserve(leaf, p):
                                      return bt.wait_in_precommit()
    mode = select_mode(modes, U_epi, M.lam)
    U_floor = U_ale + (0.0 if g else U_epi)
    lam = max(M.efs.risk_scale(...), lam_floor(U_floor))
    k = M.c_ras_wm.certified_prefix(M.ach.propose(x_prime,M.vista.H),...,wm_preds)
    out = (M.commit_window.execute(leaf,p,mode.a[:k],lam) if leaf and leaf.ready
           else M.pi_sigma.prefix_dispatch(mode.a[:k])*lam)
    M.bti.submit_async(bt.trace, leaf, p, U_epi, M.rsr)
    return out, (U_ale,U_epi), bt.status
```

## 4. 推导

**引理 19（提交边界的 epistemic→aleatoric 相变）** t > t† 后，任何允许动作对模态身份的互信息增益为 0，故 VoI ≡ 0，残差 U_epi 必须并入 U_ale。系：可约不确定性必须在 t† 前处置；R70 的 CVL 就是「是否到了最后一次处置机会」。

**引理 20（守卫支配的组合可靠性）** 满足定义 316(a)–(d) 时，任一执行前缀的提交叶执行时 Pre_c 成立、写入 ψ_c ⊨ Post_c，后续读该谓词的守卫不被未认证的写欺骗。系：安全从 R68「单条轨迹前缀认证」升级为「树结构 + 节点契约认证」。

**引理 21（稳健投影的 TOCTOU 鲁棒性）** 若 `s_m(p†) > L_d·Δt + ε_toctou` 且 `min_δ Q_place(p†+δ) > 0`，提交瞬间 ψ 成立概率 ≥ 1−δ_geo。即往可行域内部收缩等价于为「检查-使用」时差买保险；贴边放置即使检查时安全也会在 Δt 内失效。

**引理 22（承诺后悔界与分级门槛）** `E[regret] ≤ κ(1−p_g) + C_rec(1−π_rec) ≤ R_max`；对 κ=∞ 的不可恢复动作必须 p_g → 1，否则期望后悔无界、任何有限安全预算都不允许提交。系：分级证据门槛 τ_κ 是后悔界的反解，不是拍脑袋。

**定理 18（ANCHOR 严格包含 FLUID-RAS）** 无提交叶（全 ∈ 𝒜_rev）时守卫/提交逻辑旁路，逐指令退化为 FLUID-RAS；有提交叶时仅在提交处施加额外约束（新鲜守卫、ψ⊑Pre、恢复可行、分级证据、原子预留），不取消 R68/R69 任何安全约束 ⇒ 任意状态期望风险 ≤ FLUID-RAS，安全侧不让步。

**定理 19（无活锁与迟滞有界）** 进展测度 μ 严格下降、交互预算有限、Selector 带滞回 h ⇒ 有限 tick 内进入 Success/Failure/显式等待求助态；翻烧饼次数 ≤ J_span/h + O(1)，不出现无穷「问—等—再问」。

**定理 20（静态可验证 + 运行期 O(1)）** 树上的 dominator 分析对「守卫支配提交叶」可靠且完备；TSC 证书可离线生成并缓存，运行期只做 O(1) 新鲜度/预留复核，放置可行性计算仅在提交路径支付。

## 7. 本轮最大风险

**一句话**：ANCHOR-RAS 的安全性完全押在「守卫看到的世界就是提交那一刻的世界」这一前提上——**行为树只能保证结构上没绕过守卫，保证不了守卫本身新鲜且语义正确；一旦放置可行性模型或守卫时效被系统性偏置/共模欺骗，系统会以「结构已认证」的自信执行一次不可撤回的落子，而这种错误既不能靠放慢（λ 对离散提交无效）也不能靠事后追问（提交后 epistemic 已冻结）来补救**——**一个错误的提交，比任何数量的错误动作都更难挽回**。

**次级风险与缓解**：守卫陈旧/TOCTOU（定义 320 + 引理 21 + E304）；不可恢复动作被误当可恢复（定义 311/322 + 分级门槛 + E306）；共模证据欺骗（R69 正交证据纪律 + 定义 327 审计 + E310）；语义放置误泛化（Sem + 人类求证 + E309）；行为树活锁/震荡（进展测度 + 滞回 + 定理 19）；κ/可行性模型的标定误差（保守内缩 + 「拒绝提交优先于硬放」）。
