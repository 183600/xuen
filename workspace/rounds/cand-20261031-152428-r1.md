# 第 1 轮（承接第 12 轮 CHUNK-SERVO）· GRIP-MESH：把 Dex1 夹爪的位置反馈变成免费接触传感器，用 33k 演示先验和多机评测网格打最后 3 毫米

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新灵感循环第 1 轮，三个词是「多机评测」「夹爪控制」「数据集」。本轮不推倒第 12 轮 CHUNK-SERVO，而是补上它的三个盲区：**手臂位姿闭环有了，夹爪接触还是开环；单机评测有了，多机部署还没有；数据集只用来训练，还没用来做先验。**

## 0. 先给结论：榜首不到 30%，而夹爪位置反馈是一个被忽略的接触传感器

截至 2026-10-31，官网首页/榜单的表格位置仍显示「即将发布 / Coming Soon」，`leaderboard_data.json` 仍返回 8 个预览模型：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、PI-0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。这些数字不能当真实榜单用：**232/256 个任务成功率不是 10% 的整数倍**（10 次真机运行只可能产生 0/10/…/100），**每个模型内部 `step_score` 几乎是 `success_rate` 的线性函数**（MolmoAct2 R²=0.9999996，WALL-OSS-0.5 R²=0.9999998，斜率 1.313/1.365，截距≈0），**跨模型任务成功率平均相关仅 0.098**（最小 -0.208，最大 0.353）。结论：JSON 是预览/占位数据，不能用于难度排序或失败分布推断（B）。

但预览数字仍然说明一个事实：**头尾只差 9.2pp，没有哪个架构拉开代差**。我的判断是，所有模型共享同一个执行瓶颈，不是语义，也不是 3D 感知，而是：

1. **夹爪是开环的**。VLA 输出 1 维夹爪命令，evaluator 执行完整个 chunk 才给下一次观测；没有力/触觉，夹爪闭没闭住、夹的是 0.5 mm 还是 1.5 mm、有没有滑，模型都不知道。最后 3 毫米的夹持失败，会被记成“任务失败”，但根因在夹爪。
2. **10 次评测全部是泛化条件**。官方手册明确：每个任务 10 次，5 类泛化各 2 次（位置、干扰物、桌面背景、未见物品、人为干扰），**没有 nominal trial**。所以“正常数据训练 + 正常场景测试”这条路根本不存在；数据集又只有成功轨迹，没有失败分布。
3. **评测是多机、远程、N 端口**。提交要从 8765 起暴露 N 个连续端口，每端口独立交互、`reset()` 状态隔离；一个端口的状态泄漏、延迟尖峰或夹爪零点漂移，会直接损失 1/N 的分数。

所以本轮的押注是 **GRIP-MESH**：

> 不换更大的 VLA，也不加第二个学习模型。把 Dex1 已经暴露的**夹爪位置反馈**当成免费接触传感器：用 33k 成功演示挖出「任务 × 主动臂 × 相位」的夹持宽度先验（GEL），用确定性状态机在 chunk 内做夹爪反射（GRIP-REFLEX），用每端口会话隔离/标定/延迟预算把 N 台机器人接成一张评测网格（PORT-MESH）；数据配方按 5 条泛化轴分层（GEN-STRAT），可选在同一 WLA checkpoint 上加一个夹爪辅助头（GRIP-AUX）。

一句话：**CHUNK-SERVO 管最后 3 厘米的手臂位姿，GRIP-REFLEX 管最后 3 毫米的夹持；夹爪位置不是“低维动作”，而是“接触观测”。**

三个主投创新点：

1. **GEL（Gripper Event Library）**：从 33,276 条成功演示中挖 phase-conditioned 夹持宽度、闭合时序、主动臂、释放时序，导出每任务先验 JSON；不是模型，是查表先验。
2. **GRIP-REFLEX**：命令-状态偏差 + 腕部相机二次确认，检测空闭/接触/滑移/卡滞/释放；在 5 步 chunk 内做确定性修正；不是第二个学习模型。
3. **PORT-MESH**：N 端口共享一个 VLA，但每端口独立 session、标定、账本和超时回退；把“多机评测”从部署细节变成可验证指标。

两个保留/可选创新点：

4. **GEN-STRAT**：按 5 条泛化轴做分层数据配方；空间随机化优先，外观增强其次；修官方 loader 忽略 `weight` 的问题。
5. **GRIP-AUX**（stretch）：在同一个 WLA checkpoint 的 action expert 上加辅助 contact/stall/slip 预测头；只在 G2/G3 过关后做。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **多机评测** | PORT-MESH：N 端口、session 隔离、每端口夹爪/相机标定、deadline-aware batching、trial ledger、p99 延迟门 | 不做“N 个独立模型”；不假设 N 已知；不把端口失败当模型失败 |
| **夹爪控制** | GEL + GRIP-REFLEX：位置反馈当接触传感器；任务/相位/主动臂先验；空闭/滑移/卡滞/释放状态机 | 不做力/触觉闭环（API 没有）；不把夹爪当纯回归维度；不在 chunk 内假设能拿到新观测 |
| **数据集** | GEL 挖 33k 成功轨迹；GEN-STRAT 按泛化轴分层；腕部视频只在事件窗口解码 | 不把成功数据当失败数据；不假设 step_score 独立；不迷信 169 h 全量视频解码 |

## 1. 本轮核实的事实（只列会改变方案的）

### 1.1 赛事状态：榜单仍是预览，规则没变

- 官网首页、`challenges.html`、`leaderboard.html`、`runs.html` 在 2026-10-31 的表格位置均显示 **“Coming Soon / 即将发布”**；`leaderboard_data.json` 仍返回 8 个模型和 32 个任务的预览值，但详情视频是占位符，缺少真实 episode 记录。[S1]
- 官方挑战页写 **32 个任务、32,000 条演示、169 小时**（取整）；HF 逐数据集求和是 **33,276 episodes / 18,282,246 frames / 169.28 h @30fps**。[S1][S4]
- 规则（中文/英文手册一致）：仅**通才模型赛道**，所有任务必须同一模型；32 任务 × 每任务 10 次独立运行；10 次中 **5 类泛化各 2 次**：位置、干扰物、桌面背景、未见物品、人为干扰；**没有 nominal trial**；单次上限 **180 s**；排名先总平均成功率，再总平均步骤分，再更早提交；另有**不计分的单任务测试通道**。[S3]
- 评测跨 **N 台机器人**；提交从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态必须隔离。[S2]
- 榜单 JSON 的证据（B）：232/256 个任务成功率不是 10% 的整数倍；每个模型内部 step_score 与 success_rate 近似严格线性；跨模型任务相关仅 0.098；详情视频占位。**在官方正式榜单发布前，只能当预览，不能当难度表。**

### 1.2 API：四路 RGB、无深度/力/触觉，夹爪只有 1 维位置

| 类别 | 键 | 维度/类型 | 备注 |
|---|---|---|---|
| 图像 | `cam_left_high` / `cam_right_high` / `cam_left_wrist` / `cam_right_wrist` | 4 × RGB 480×640 | 无 depth、无 camera_info、无点云 |
| 手臂 | `left_arm` / `right_arm` | 7 + 7 | 关节角 |
| 末端 | `left_ee_pose_gripper_base` / `right_ee_pose_gripper_base` | 6 + 6 | xyz + rpy，base 系 |
| 夹爪 | `left_gripper` / `right_gripper` | 1 + 1 | **唯一接触相关信号** |
| 下身体 | `lower_body` | 15 | 含腰部 3 关节 |
| 语言 | `language` | str | `obs_delta_indices` offset 必须 `[0]` |

- 动作：`control_space` 仅 `"joint"` 或 `"ee"`，互斥；EE 模式为 `action.left_ee_pose_gripper_base`/`right_ee_pose_gripper_base` [6]（**绝对目标位姿**）、`left_gripper`/`right_gripper` [1]、`pivot` [7]；无 depth/force/torque/tactile。[S2]
- `action_chunk_size` 由选手选择，**≥1 且整个提交固定**；官方示例 `ACTION_CHUNK_SIZE = 8`，WLA 默认 30；evaluator 按 chunk 顺序执行直到下次 `get_action`，**chunk 内没有新观测/打断**。不能运行时自适应 chunk 长度。[S2][S6]
- `metadata.token` 握手校验一次；每次 `get_action` 的 `meta.token` 必须匹配；`obs_delta_indices` 的键决定发送哪些观测；evaluator 记录逐调用延迟/波动/动作统计。[S2]
- `reset()` 返回 `{"ok": True}`；evaluator 保证“有效 reset 后才能下一次交互”，但**每端口状态隔离必须由选手保证**。[S2]

### 1.3 数据：33,276 eps / 169.28 h；腕部有内参；Dex1 是位置控制夹爪

- 32 个 HF 数据集合计 **33,276 episodes / 18,282,246 frames / 169.28 h @30fps**；单任务 969–1,533 episodes。[S4]
- 四路视频：`head_stereo_left/right`、`wrist_left/right`，480×640，AV1，30fps。[S4]
- `camera_params.head_stereo`：左右内参、畸变、R/T、基线 **58.2526 mm**、`rectified: true`；示例 HangCup `fx≈282.37`。[S4]
- **重要更正**：`camera_params.wrist_left.color` / `wrist_right.color` **有完整彩色内参**（HangCup 示例 `fx≈436.406, fy≈435.922, cx≈323.922, cy≈242.933`）及 inverse Brown-Conrady 畸变；第 12 轮“腕部无内参”是错误判断。缺的是**手眼外参**，不是内参。[S4]
- Dex1-1 夹爪（官网）：90 mm 行程、5–120 N、50–375 mm/s、**0.1 mm 分辨率**、全行程闭合 **0.24 s**、1 kHz 控制、内部有角度/速度/力矩/温度反馈；但挑战赛 API 只暴露夹爪位置标量 `[1]`。[S5][S2]
- 数据中 `observation.state.*_gripper` 范围约 **-0.28 ~ 4.83**；`action.*_gripper` 范围 **0 ~ 4.5**（不是硬件 5.5）；`action.gripper_controls` 为 4D `[left_trigger, left_squeeze, right_trigger, right_squeeze]`，trigger=10 开、0 合，squeeze 为力/挤压。[S4]
- `observation.state.recomputed_ee_valid` 在全部 32 任务中 **min=max=1**（数据质量标志全有效）；`state_d435` 为头相机在 base 系 6D 位姿；`waist_state_joint = lower_body[-3:]`，可用腰部关节 + URDF 恢复头相机外参。[S4]
- 数据集只有成功轨迹：没有失败、没有放弃、没有“夹空”的负样本；所有先验都必须从成功轨迹的**事件结构**里挖，不能假设有失败分布。[S4]

**已做的三任务夹爪事件分析（B）**：从 HF parquet 的 state/action 列直接挖闭合事件；事件定义为“命令从 >4.3 进入 <2.5 并保持 ≥10 帧”；夹持宽度取闭合区间内 `observation.state.*_gripper` 的最小值（接触/ stall 宽度）。结果：

| 任务（file-000） | episode | 主动臂/事件 | event1 stall 中位（IQR） | event2 stall 中位（IQR） | 事件数分布 |
|---|---:|---|---:|---:|---|
| **HangCup** | 719 | 右臂钩挂 | **0.032**（-0.005, 0.064） | -0.023（-0.049, 0.012） | 右：560×1、34×2、2×3、1×4；左：仅 1 个 episode 有事件 |
| **PlugInEthernet** | 211 | 双臂，左先右后 | 左 **0.586**（0.570, 0.597）；右 **0.084**（0.070, 0.100） | 左 **1.137**（1.124, 1.151）；右 **0.440**（0.405, 0.476） | 左：197×2、9×3、3×1、2×4；右：108×2、98×1、2×3 |
| **StackBowls** | 412 | 双臂，左主右辅 | 左 **0.167**（0.097, 0.236）；右 **0.239**（0.134, 0.303） | 左 0.128（0.085, 0.233）；右 0.201（0.138, 0.278） | 左：281×1、32×2、1×3；右：220×1、50×2、1×3 |

- 按 4.5–5.5 单位对应 90 mm 估算，1 单位约 16–20 mm；0.03 单位约 0.5 mm，1.14 单位约 18–23 mm。**同一任务内，event1 和 event2 的夹持宽度可以差 2–5 倍**：PlugInEthernet 左 0.586 vs 1.137，右 0.084 vs 0.440。任务级阈值必然误判，必须 **phase-conditioned**。
- 负值/接近 0 表示夹爪完全闭合；数据存在零点偏移，在线应使用标定后的相对宽度（`g_t - g_closed`），不要直接比较绝对负数。
- HangCup 是负对照：右夹爪闭合到 ~0.03（接近全闭）是**正确的钩挂动作**，不是“夹空失败”。所以“状态没到物体宽度就报错”会在 HangCup 上大量假阳性；正确做法是查该任务/该相位的先验，而不是全局阈值。
- 事件时长（中位，@30fps）：PlugInEthernet 左 event1 98 帧（3.27 s）、event2 148 帧（4.93 s）；右 event1 58 帧（1.93 s）、event2 296 帧（9.87 s）。右 event2 更像长保持/运输，而非第二次独立闭合（需相位标签验证）；状态机必须区分“闭合事件”和“保持阶段”。
- 局限：成功数据没有“滑移/夹空”的负标签；夹爪位置只能检测“闭合宽度”，不能单独检测“纯滑移”（指尖位置可能保持而物体在指间滑）。滑移必须靠腕部相机二次确认（见 3.2）。

### 1.4 官方 WLA：6B、2500h、64 任务、chunk 30、24GB 微调、LoRA 已开源

- UnifoLM-WLA-1.0：6B 参数、约 2,500 h 真机数据、64 任务；默认 `chunk_size=30`、`target_fps=30`、4 步扩散；冻结 VLM 微调 action head 单卡 **24 GB**；2026-09-28 已开源 Base 权重、微调代码及 **LoRA 微调代码**；模型服务器目前 Dex1-only。[S6]
- 动作适配器把模型 54D action 映射到挑战赛 21D（具体维度切分以代码为准）；`pivot` 的逐维语义仍需实测。[S6][S2]
- 训练文档明确：多数据源采样按样本数比例，**当前实现不应用配置的 `weight`**；要任务重加权需改 loader 或复制数据。这对 GEN-STRAT 是硬约束。[S6]
- WLA 的 30 步 chunk 与挑战赛 `action_chunk_size` 解耦：可以生成 30 步、只返回前 k 步，k 由提交固定；也可以用官方模型服务器直接设 k。k=5/8 是“重规划周期”，不是模型能力。[S6][S2]

### 1.6 外部证据：位置/电流接触反馈、fleet 数据、chunk 时序、泛化增强

- **接触反馈**：`Current as Touch`（arXiv 2607.03529）用电机电流/关节状态做本体接触反馈；挑战赛没有电流，但夹爪位置反馈是弱化版。`HapticVLA`（2603.15257）、`ReTouch`（2608.01824）、`FAVLA`（2602.23648）说明接触/力预测可以和 VLA 结合，但都需要额外传感器或高频控制；本轮只用已有的夹爪位置，避免硬件假设。[S7][S11]
- **多机/fleet**：`Learning from Fleet Experience`（96 robots，2610.25736）和 `Learning while Deploying`（16 robots，2605.00416）说明多实例数据/部署能提升跨场景泛化；PORT-MESH 的每端口标定/账本正是把“多机”从负担变成可观测变量。[S8]
- **chunk/接触时序**：`TRACT`（2607.29285）、`RoboPace`（2610.09696）、`Adaptive Action Chunking`（2604.04161）说明 chunk 长度/接触阶段需要随任务调整；挑战赛不允许运行时改 `action_chunk_size`，所以只能在固定 k 内做相位/反射，这反而让 GEL/GRIP-REFLEX 更有价值。[S9]
- **泛化增强**：`RoboAug`（2602.14032）、`SEVO`（2605.11114）、`Pose6DAug`（2606.20118）、`ROSIE`（2302.11550）支持背景/干扰物/未见物/位姿增强；GEN-STRAT 的空间随机化优先、外观增强其次，与这些证据一致。[S10]

## 2. 诊断：三个“开环”

| 开环 | 现象 | 后果 | 本轮对策 |
|---|---|---|---|
| **夹爪开环** | 夹爪命令是 1 维回归；chunk 内没有新观测；无力/触觉 | 夹空、夹偏、滑移、卡滞都到任务失败才被发现 | GEL 先验 + GRIP-REFLEX 状态机 + 腕部二次确认 |
| **泛化开环** | 10 次全是 5 类泛化；训练数据只有成功 nominal 轨迹 | 位置/背景/干扰物/未见物/人扰任意一项掉点，平均分直接掉 | GEN-STRAT 分层配方；空间随机化优先；编辑检测/恢复 |
| **多机开环** | N 端口、远程、每端口独立 reset；没有每端口标定/账本 | 一个端口状态泄漏/延迟尖峰/夹爪零点漂移损失 1/N | PORT-MESH session 隔离 + 标定 + deadline guard + ledger |

本轮只主投第一个开环，第二/第三个开环用“足够好”的工程解，不展开成新模型。

## 3. 方法：GRIP-MESH

### 3.1 GEL：从 33k 成功演示挖“任务 × 主动臂 × 相位”的夹持先验

**输入**：32 个 HF 数据集的 `observation.state.*_gripper`、`action.*_gripper`、`action.gripper_controls`、`episode_index`、`frame_index`；可选腕部视频只在事件窗口解码。

**流程**：
1. 按 episode 切分，检测 `action.*_gripper` 从开（>4.3）到合（<2.5）的闭合并沿；要求低命令保持 ≥10 帧，避免抖动。
2. 对每个闭合区间，取 `observation.state.*_gripper` 的最小值作为 **stall 宽度**；取命令低电平持续时间为 **闭合时长**；取释放（命令回到 >4.0）为 **释放时刻**。
3. 用 `action.gripper_controls` 的 trigger/squeeze 和双臂事件顺序，给事件打 **相位** 标签（approach/close/hold/transport/release/recover）和 **主动臂** 标签。
4. 按任务 × 臂 × 相位聚合：中位/IQR/q05/q95、事件数分布、闭合时长、保持时长、释放时长。
5. 导出 `gel_priors.json`：每任务每臂每相位的 `stall_lo/stall_hi/stall_med/close_dur/hold_dur/release_dur/active_arm_prob`。
6. 在 held-out episode 上检查先验覆盖：event1/event2 的 stall 宽度分位数、相位顺序、主动臂准确率。

**输出**：查表先验，不是模型；CPU 可跑；不需要全量解码 169 h 视频。**用途**：GRIP-REFLEX 的阈值、VLA 夹爪动作的修复、任务/相位门控、异常检测。

**与现有方案的差异**：不是“再训一个夹爪模型”，也不是“全局夹爪阈值”；它把成功演示里的**事件结构**变成 per-task/per-phase 先验，直接利用挑战赛数据集的 32 任务覆盖。与 DG-KEYFRAME 的区别：DG-KEYFRAME 检索“目标-夹爪相对位姿”，GEL 检索“夹持宽度/时序”；两者可以合并成一个先验库。

### 3.2 GRIP-REFLEX：用位置反馈做“免费接触传感器”

**信号**：`u_t`（VLA 夹爪命令）、`g_t`（夹爪状态）、`e_t = u_t - g_t`、`ġ_t`（状态速度）、腕部图像 `c_t`（可选）、EE 位姿（判断是否在接近/运输）。

**事件定义**：

| 事件 | 判据（示意） | 动作 |
|---|---|---|
| **空闭** | `g_t` 降到该任务/相位先验的下界以下，且 `|e_t|` 小 | 停止继续闭合；抬腕/重试/换抓取点 |
| **接触/夹持** | `g_t` 进入先验 `[stall_lo, stall_hi]`，`ġ_t≈0`，`|e_t|` 小 | 保持；进入 transport |
| **滑移** | `g_t` 在保持段缓慢上升/抖动，或腕部图像中物体相对指尖位移 | 加大闭合命令/暂停/重新抓取 |
| **卡滞** | `|e_t|` 持续大，`g_t` 不跟随，超过阈值时长 | 反向微开、重试、报警 |
| **释放** | `u_t` 回到开区间，`g_t` 跟随上升 | 进入 recover；清空 phase |

**控制律**（示意）：

```text
u_grip = clip(u_vla + Δ_reflex, 0.0, 4.5)
Δ_reflex = 0                      if phase == APPROACH
         = -k_close * (g_t - w_lo) if phase == CLOSE and g_t < w_lo   # 空闭，停止
         = +k_hold  * (w_hi - g_t) if phase == HOLD and g_t > w_hi    # 滑移，补夹
         = +k_jam   * sign(e_t)    if jam_detected                   # 卡滞，反向微开
```

- 修正幅度必须小（例如每步 ≤0.05–0.1 单位），避免和 VLA 的语义动作打架；夹爪反射只在 `CLOSE/HOLD/RELEASE` 相位生效，`APPROACH/TRANSPORT` 不干预。
- **空闭检测是任务相关的**：HangCup 的先验 `w_lo≈0`，所以“闭合到 0”不报空闭；PlugInEthernet 左 event1 的 `w_lo≈0.586`，闭合到 0 才报空闭。这正是 GEL 的作用。
- **滑移必须二次确认**：夹爪位置只能检测“宽度变化”，不能检测“指尖位置不变但物体在滑”。用腕部相机在保持段取两帧，比较物体/指尖相对位移；只有位置+视觉都异常才触发补夹，降低假阳性。
- **时序**：30Hz 下 5 步 chunk = 167ms；Dex1 全行程闭合 0.24s；夹爪命令到状态约 2–3 帧滞后。反射的检测延迟预算 ≤3 帧（100ms），否则等检测到已经进入下一个 chunk。
- **合规**：GRIP-REFLEX 是确定性控制器，没有学习权重；不是第二个模型；不违反“同一模型”规则。

### 3.3 PORT-MESH：把 N 台机器人接成一张可验证的评测网格

**问题**：N 未知；端口必须连续；每端口独立 reset；共享一个 6B 模型时，任何全局可变状态都会造成跨端口污染；网络 RTT 和 GPU 排队会让 p99 延迟超过 chunk 周期。

**设计**：
- **Launcher**：读 `N`（环境变量/配置），从 8765 起启动 N 个 `PolicyService`；每个 service 有自己的 `SessionState`（plan cache、phase、goal、reflex 状态、gripper 标定、token、episode id）。
- **ModelBackend**：一个共享 WLA 权重 + 无状态推理；请求带 `session_id`，禁止任何跨请求的可变缓存；batch window 10–20ms；每请求返回固定 `k` 步。
- **Per-port calibration**：夹爪开/合偏移与尺度、腕部内参、头相机外参（用腰部关节 + URDF）、RTT 基线；存 JSON；每次 reset 后重新检查夹爪零点。
- **DeadlineGuard**：p99 推理时间超过 `k/30s` 的 70% 时，返回**同一模型**的更短 chunk（例如 k=5→3）或上一步的安全保持动作；这是控制器回退，不是第二个模型。注意：`action_chunk_size` 在 metadata 固定，不能运行时改；这里说的是**模型内部生成长度/返回长度**，需要和 evaluator 的固定 k 兼容——最稳妥是固定 k=5，回退只做“保持/微动”，不改 k。
- **TrialLedger**：逐 `get_action` 记录端口、episode、step、时间戳、延迟、动作统计、夹爪事件、反射触发；用于失败归因（模型/端口/网络/标定）。
- **N 的两种部署**：N≤2 且显存允许 → N 个模型副本（最稳）；N≥3 或显存不足 → 共享 backend + 严格 session 隔离 + 压测；两种都通过 G5/G6 才提交。

**指标**：p50/p99 `get_action` 延迟、端口间延迟方差、reset 后状态泄漏测试、每端口成功率方差、GPU 显存峰值、端口重启次数。

### 3.4 GEN-STRAT：10 次全是泛化，数据配方必须按轴分层

- 5 条轴：位置、干扰物、桌面背景、未见物品、人为干扰；每条轴 2 次。**空间随机化优先**：物体位姿、相机位姿、桌高、初始关节角；这是最便宜、最通用的泛化。
- **外观增强其次**：背景纹理/颜色、干扰物 copy-paste、未见物品替换（用 3D 资产/生成模型）；不要只做像素噪声。
- **人为干扰**：用 CHUNK-SERVO 的编辑检测/恢复；训练时注入“目标被移动/遮挡”的编辑对，学会重规划。
- **数据分层**：按 session/背景/物体/位置聚类，做 group split；验证集必须包含未见背景/未见物体/位置偏移，不能随机切帧。
- **loader 约束**：官方 WLA loader 忽略 `weight`；要任务重加权就复制数据或改 loader；不要假装 `weight` 生效。[S6]
- **不做**：不把成功数据当失败数据；不假设 32 任务等难度；不把预览榜单的任务排名当采样权重。

### 3.5 GRIP-AUX（stretch）：同一 checkpoint 的夹爪辅助头

- 在 WLA action expert 的共享特征上加一个轻量 MLP 头，预测：接触概率、stall 宽度、滑移风险、卡滞风险；标签从 `observation.state.*_gripper` 和 GEL 事件自动生成，不需要人工标注。
- 联合损失：`L = L_action + λ_contact L_contact + λ_stall L_stall + λ_slip L_slip`；推理时只用来门控 GRIP-REFLEX，不替代动作头。
- **合规**：辅助头在同一个 checkpoint 内，仍是一个模型；如果规则对“模型”定义有疑问，默认不启用，只保留确定性 reflex。
- **门槛**：只有 G2（离线反射）和 G3（仿真）都过，且 G4 单任务 A/B 有正收益，才做；否则砍掉。

### 3.6 与 CHUNK-SERVO 的整合

```text
VLA（30 步意图，每 5 步重规划）
  ├─ 手臂：CHUNK-SERVO（腕部/头部视觉伺服，最后 3 cm）
  ├─ 夹爪：GRIP-REFLEX（GEL 先验 + 命令-状态偏差 + 腕部二次确认，最后 3 mm）
  └─ 相位：FACT-VLA（approach/close/hold/transport/release/recover）
        └─ PORT-MESH（N 端口 session/标定/延迟/账本）
```

- 5 步 chunk 内：第 1 步用 VLA 动作；第 2–5 步按 CHUNK-SERVO 修正手臂、按 GRIP-REFLEX 修正夹爪；第 5 步结束再请求新 chunk。
- 夹爪反射不改变手臂轨迹，只改夹爪标量；如果反射触发“重试”，手臂抬腕/后退由 CHUNK-SERVO 的 recover 相位接管。
- 保留 CHUNK-SERVO 的 5 步闭环；**不保留**“30Hz 广域网伺服”这种不现实设定；RTT 未知，先用 5 步/167ms 作为控制周期，实测后再调。

## 6. 风险与合规

- **假阳性**：HangCup 空闭是正确动作；必须用 GEL 先验门控，不能全局阈值。
- **纯滑移**：夹爪位置不能单独检测；必须腕部相机二次确认；否则不触发补夹。
- **API 语义**：数据命令 0–4.5，硬件 5.5；evaluator 的实际范围/方向/单位未实测；先用单任务通道标定。
- **标定漂移**：每端口夹爪零点/尺度不同；每次 reset 后检查；失败则用保守阈值。
- **单模型合规**：GRIP-REFLEX/GEL/PORT-MESH 都不是学习模型；GRIP-AUX 必须同一 checkpoint；有疑问就不启用。
- **并发/延迟**：共享 backend 的 p99 可能超过 chunk 周期；N 副本优先；DeadlineGuard 只做保持，不改固定 k。
- **数据泄漏**：GEL 先验必须按 session/任务 held-out 验证；不能把测试 episode 挖进先验。
- **评估噪声**：每任务 10 次，成功率标准误约 0.15；单任务 +10pp 需要配对/多任务聚合，不能只看一次。
- **时间**：先做 G0–G2，G4 不过就砍 GRIP-AUX；不要一开始就训大模型。

## 7. 一句话押注

**把夹爪从开环末端执行器变成闭环接触传感器——GEL 先验 + GRIP-REFLEX + PORT-MESH，比再训一个更大的 VLA 更便宜、更合规、更直接打最后 3 毫米。**

# 第 1 轮产物 · GRIP-MESH 技术报告：夹爪位置反馈驱动的接触闭环、多机评测网格与 33k 演示先验

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本报告是第 1 轮 GRIP-MESH 的工程产物，承接第 12 轮 CHUNK-SERVO；**不替换** CHUNK-SERVO 的手臂视觉伺服，而是补上夹爪接触闭环、多机评测网格和数据先验。证据等级：**A**=官方文档/数据直接核实；**B**=我们对公开数据的复算；**C**=设计假设，待单任务通道/仿真验证。

## 0. 执行摘要

- **榜单仍是预览**：2026-10-31 官网榜单/Runs 表格显示 “Coming Soon”；`leaderboard_data.json` 仍返回 8 个模型，但 232/256 个任务成功率不是 10% 的整数倍，每个模型内部 `step_score` 与 `success_rate` 近似严格线性（MolmoAct2 R²=0.9999996，WALL-OSS-0.5 R²=0.9999998），跨模型任务成功率平均相关仅 0.098。结论：只能当预览，不能当难度表/失败分布（B）。
- **夹爪位置是免费接触传感器**：Dex1 是位置控制夹爪（90 mm 行程、0.1 mm 分辨率、0.24 s 全闭），API 暴露夹爪位置 `[1]`；数据集里同一任务的不同相位夹持宽度差异巨大（PlugInEthernet 左 0.586 vs 1.137，右 0.084 vs 0.440；StackBowls 左 0.167、右 0.239；HangCup 右 0.032 是正常空闭钩挂）。因此不能用任务级阈值，必须用 **task × arm × phase** 先验（B）。
- **本轮主投**：GEL（从 33,276 eps 挖夹持事件先验）+ GRIP-REFLEX（确定性夹爪反射）+ PORT-MESH（N 端口会话隔离/标定/延迟/账本）。GEN-STRAT 保留，GRIP-AUX 观察，CHUNK-SERVO+ 升级保留。
- **一句话**：CHUNK-SERVO 管最后 3 cm 的手臂位姿，GRIP-REFLEX 管最后 3 mm 的夹持；不换更大 VLA，也不加第二个学习模型。

### 1.2 提交 API（A）

| 类别 | 键 | 维度/类型 | 备注 |
|---|---|---|---|
| 图像 | `cam_left_high` / `cam_right_high` / `cam_left_wrist` / `cam_right_wrist` | 4 × RGB 480×640 | 无 depth、camera_info、点云 |
| 手臂 | `left_arm` / `right_arm` | 7 + 7 | 关节角 |
| 末端 | `left_ee_pose_gripper_base` / `right_ee_pose_gripper_base` | 6 + 6 | xyz + rpy，base 系 |
| 夹爪 | `left_gripper` / `right_gripper` | 1 + 1 | **唯一接触相关信号** |
| 下身体 | `lower_body` | 15 | 含腰部 3 关节 |
| 语言 | `language` | str | `obs_delta_indices` offset 必须 `[0]` |

- 动作：`control_space` 仅 `"joint"` 或 `"ee"`，互斥；EE 模式为绝对目标位姿 `[6]` + 夹爪 `[1]` + `pivot` `[7]`；无 depth/force/torque/tactile。[S2]
- `action_chunk_size`：选手选择，**≥1 且整个提交固定**；官方示例 `8`，WLA 默认 `30`；evaluator 按 chunk 顺序执行直到下次 `get_action`，chunk 内没有新观测/打断。**不能运行时自适应 chunk 长度。**[S2][S6]
- `metadata.token` 握手一次；每次 `get_action` 的 `meta.token` 必须匹配；`obs_delta_indices` 决定发送哪些观测；evaluator 记录逐调用延迟/波动/动作统计。[S2]
- `reset()` 返回 `{"ok": True}`；evaluator 保证有效 reset 后才交互，但**每端口状态隔离由选手保证**。[S2]

**关键推论**：夹爪是唯一能提供“接触/物体宽度”反馈的通道；chunk 内看不到新观测，所以反射必须是**基于上一帧状态 + 当前命令的短时预测/状态机**，不能等新图像。固定 k=5（167ms）是反馈周期，k=8（267ms）是更稳的折中；k=30（1s）对接触任务太慢（C）。

#### 32 任务夹爪范围扫描（B）

三任务深挖之外，我们还对 32 任务的 state/action 列做了范围扫描（只读 gripper 列，不下载视频）。两个结论：

- **主动臂差异大**：例如 HangCup 右夹爪 event1 中位 0.032、左夹爪 719 eps 中按本报告阈值仅 1 个闭合事件（第 12 轮用不同阈值曾得到 3 个，说明阈值敏感）；PourOutMedicine 左夹爪最小 **0.675**（几乎不闭合，可能一直握着药瓶），右夹爪最小 -0.045。任务级“哪个臂是主动臂”必须先验，不能默认双臂对称。
- **闭合宽度差异大**：同一任务的不同事件/不同臂可差 2–5 倍；用全局阈值会把“正常空闭/钩挂/握持”误判为失败（见 1.3.1）。

#### 1.3.1 三任务夹爪事件深挖（B）

方法：从 HF parquet 只读 `episode_index`、`observation.state.*_gripper`、`action.*_gripper`；事件定义为“命令从 >4.3 进入 <2.5 并保持 ≥10 帧”；stall 宽度取闭合区间内 state 的**最小值**（接触/夹持宽度）；按 episode 内事件顺序分 event1/event2。样本为各数据集 `file-000` 子集（全量 episodes 见上表）。

| 任务（file-000） | episode | 主动臂/事件 | event1 stall 中位（IQR） | event2 stall 中位（IQR） | 事件数分布 |
|---|---:|---|---:|---:|---|
| **HangCup** | 719 | 右臂钩挂 | **0.032**（-0.005, 0.064） | -0.023（-0.049, 0.012） | 右：560×1、34×2、2×3、1×4；左：仅 1 eps |
| **PlugInEthernet** | 211 | 双臂，左先右后 | 左 **0.586**（0.570, 0.597）；右 **0.084**（0.070, 0.100） | 左 **1.137**（1.124, 1.151）；右 **0.440**（0.405, 0.476） | 左：197×2、9×3、3×1、2×4；右：108×2、98×1、2×3 |
| **StackBowls** | 412 | 双臂，左主右辅 | 左 **0.167**（0.097, 0.236）；右 **0.239**（0.134, 0.303） | 左 0.128（0.085, 0.233）；右 0.201（0.138, 0.278） | 左：281×1、32×2、1×3；右：220×1、50×2、1×3 |

事件时长（中位，@30fps）：

| 任务 | 左 event1 | 左 event2 | 右 event1 | 右 event2 |
|---|---:|---:|---:|---:|
| HangCup | — | — | 74 f / 2.47 s | 70 f / 2.33 s |
| PlugInEthernet | 98 f / 3.27 s | 148 f / 4.93 s | 58 f / 1.93 s | 296 f / 9.87 s |
| StackBowls | 39 f / 1.30 s | 46 f / 1.53 s | 36 f / 1.20 s | 37 f / 1.23 s |

**解释**：

1. **任务/相位条件化是硬需求**。PlugInEthernet 左 event1 0.586（约 9–12 mm）与 event2 1.137（约 18–23 mm）差近 2 倍；右 event1 0.084（约 1.4–1.7 mm）与 event2 0.440（约 7–9 mm）差 5 倍。用 0.5 或 1.0 的全局“空闭阈值”必然在其中一个相位出错。
2. **HangCup 是负对照**。右夹爪闭合到 ~0.03（接近全闭）是正常钩挂；如果 reflex 把“state < 0.1”一律判为空闭，HangCup 会大量误报。正确做法：查 `HangCup/right/hook` 先验，允许空闭。
3. **右 event2 的长时长更像保持/运输**。296 帧（9.87 s）不是一次新的闭合动作，而是夹住网线后的长保持；状态机必须把“闭合事件”和“保持阶段”分开，不能每个低命令帧都触发反射。
4. **StackBowls 分布更宽**。左 0.167（IQR 0.097–0.236）、右 0.239（IQR 0.134–0.303），说明碗的抓取点/碗径变化大；先验应该用分位数区间，不是单点阈值。
5. **单位换算**：若 4.5 单位 = 90 mm，1 单位 = 20 mm；若 5.5 单位 = 90 mm，1 单位 = 16.36 mm。0.03 单位 ≈ 0.5 mm，1.14 单位 ≈ 18–23 mm。**命令空间与机械行程的精确对应必须用单任务通道实测**（C）。

注：负值/接近 0 表示夹爪完全闭合；数据存在零点偏移，在线应使用标定后的相对宽度（`g_t - g_closed`），不要直接比较绝对负数。

**局限**：成功数据没有“滑移/夹空”的负标签；stall 宽度只能说明“闭合到了多宽”，不能单独证明“夹住了”；纯滑移（指尖位置不变、物体在指间滑）必须靠腕部相机二次确认（见 5.5）。事件切分对阈值/滞后敏感，先验要用 held-out episode 验证，不能把测试 episode 挖进先验。

**为什么不能当真实榜单（B）**：

- **232/256 个任务成功率不是 10% 的整数倍**。每任务 10 次运行，真实成功率只能是 0/10/…/100；出现 27.29、37.01、9.03 这种值，说明不是 10 次真机统计。
- **每个模型内部 `step_score` 与 `success_rate` 近似严格线性**：MolmoAct2 斜率 1.313、截距 -0.003、R²=0.9999996、最大残差 0.0057；WALL-OSS-0.5 斜率 1.365、截距 -0.001、R²=0.9999998、最大残差 0.0054。跨模型斜率不同，但模型内几乎是同一个生成公式。
- **跨模型任务成功率平均相关仅 0.098**（最小 -0.208，最大 0.353）。如果这些是真实模型在同一批任务上的结果，任务难度应该正相关；接近零相关说明任务列的“难度”不是共享的。
- 详情视频是占位符，缺少真实 episode 记录；`generated_from: "gen_leaderboard.py"` 也说明是生成脚本产物。

**用途**：只能作为“预览上限/任务名/模型名”的参考；**不能**用于任务难度排序、失败分布推断、采样权重、或证明 SOTA。真正的难度/失败分布只能来自单任务不计分通道。

## 3. 问题形式化

### 3.1 符号

- 时间 `t`，控制频率 `f=30 Hz`（待实测）；chunk 长度 `k`（提交固定，建议 5 或 8）。
- 夹爪命令 `u_t ∈ [0,4.5]`（数据范围；API 语义待实测）；夹爪状态 `g_t ∈ [-0.3,4.8]`。
- 误差 `e_t = u_t - g_t`；状态速度 `ġ_t = g_t - g_{t-1}`。
- 相位 `φ_t ∈ {APPROACH, CLOSE, HOLD, TRANSPORT, RELEASE, RECOVER}`。
- 先验 `P(w | task, arm, φ)`：`w` 是 stall 宽度；用中位/IQR/q05/q95 表示。
- 任务/臂/相位的事件库 `GEL = { (task, arm, φ) → (w_lo, w_hi, w_med, d_close, d_hold, d_release, p_active) }`。

### 3.2 夹爪事件模型

**闭合事件检测**（离线/在线共用）：

```text
if u_{t-1} > τ_open and u_t < τ_close and same_episode(t, t-1):
    start = t
    while same_episode(t, start) and u_t < τ_release:
        t += 1
    end = t
    if end - start >= d_min:
        event = {start, end, w = min(g[start:end]), d = end-start}
```

推荐初值：`τ_open=4.3`、`τ_close=2.5`、`τ_release=2.5`、`d_min=10`（@30fps，约 0.33s）。这些值必须用 held-out 事件验证；不同任务可微调，但不能用测试 episode。

**先验**：对每个 `(task, arm, k-th event)` 聚合 `w` 的分位数。在线时用相位/事件序号选择先验；若相位未知，用最近一次事件序号 + 时间预测。

**判据**：

- **空闭**：`g_t < w_lo - margin` 且 `|e_t| < e_small`，持续 `T_empty` 帧。
- **接触/夹持**：`w_lo ≤ g_t ≤ w_hi` 且 `|ġ_t| < v_stall`。
- **滑移**：保持段 `g_t` 上升超过 `Δ_slip`，或腕部相机物体-指尖相对位移超过 `Δ_px`。
- **卡滞**：`|e_t| > e_jam` 持续 `T_jam` 帧。
- **释放**：`u_t > τ_open` 且 `g_t` 跟随上升。

### 3.3 反射控制律

```text
Δ = 0
if φ == CLOSE and g_t < w_lo - margin:
    Δ = -k_close * (w_lo - g_t)          # 停止继续闭合，避免夹空/过载
elif φ == HOLD and g_t > w_hi + margin:
    Δ = +k_hold * (g_t - w_hi)           # 补夹，抵抗滑移
elif jam_detected:
    Δ = +k_jam * sign(e_t)               # 反向微开，解除卡滞
u_grip = clip(u_vla + Δ, 0.0, 4.5)
```

- `k_close/k_hold/k_jam` 初值 0.2–0.5，每步修正上限 0.05–0.1 单位；用仿真/单任务通道调。
- 只在 `CLOSE/HOLD/RELEASE` 相位生效；`APPROACH/TRANSPORT` 不干预。
- `Δ` 不改变手臂轨迹；需要重试时由 CHUNK-SERVO 的 `RECOVER` 相位抬腕/后退。
- 安全：命令不能超过 4.5；状态异常（`g_t` 突变/NaN）时回退到“保持当前命令 + 报警”。

### 3.4 时序预算

| 项 | 数值 | 备注 |
|---|---:|---|
| 控制频率 | 30 Hz | 默认；待实测 |
| 5 步 chunk | 167 ms | 推荐反馈周期 |
| 8 步 chunk | 267 ms | 更稳，但接触反应慢 |
| Dex1 全闭 | 240 ms | 硬件规格 |
| 夹爪命令→状态滞后 | 2–3 帧（67–100 ms） | 数据观察（B） |
| 反射检测预算 | ≤3 帧（100 ms） | 否则进入下一个 chunk |
| 端到端预算 | 检测 + 推理 + RTT ≤ k/f | k=5 时 ≤167 ms；目标 ≤100 ms |

**含义**：k=5 时，反射必须在 100ms 内完成“读数→判定→改命令”；如果 RTT 已占 100ms，纯远程反射不可行，必须把反射放在**本地 policy 进程**（夹爪状态是观测的一部分，不需要额外网络往返）。这是 GRIP-REFLEX 放在 policy 侧、而不是模型服务器侧的原因。

### 3.5 多端口服务

- `N` 个端口 `8765..8765+N-1`；每端口一个 `PolicyService`，独立 `SessionState`。
- 共享 `ModelBackend`：无状态推理；请求带 `session_id`；batch window 10–20ms；禁止跨请求 KV/缓存。
- 每端口标定：夹爪开/合偏移、尺度、腕部内参、头相机外参（腰部关节 + URDF）、RTT 基线。
- `DeadlineGuard`：p99 超过 `0.7*k/f` 时，返回保持/微动（同一模型/控制器），不改固定 k；如果连续超时，降级到 N 副本或保守 k。
- `TrialLedger`：端口、episode、step、时间戳、延迟、动作统计、夹爪事件、反射触发、异常。

### 3.6 泛化轴

| 轴 | 训练时 | 测试时 | 最小对策 |
|---|---|---|---|
| 位置 | 物体/相机/桌高/初始关节随机化 | 位置偏移 | 空间随机化优先；CHUNK-SERVO 相对目标 |
| 干扰物 | copy-paste/额外物体 | 桌面多物 | 检测+忽略；GEN-STRAT 增强 |
| 背景 | 纹理/颜色/光照 | 新桌面 | 外观增强；分割/归一化 |
| 未见物品 | 3D 资产/生成替换 | 新物体 | 形状/语义泛化；夹爪先验按宽度区间 |
| 人为干扰 | 编辑对/遮挡/移动 | 人移动物体 | 编辑检测+重规划；CHUNK-SERVO recover |

## 4. 数据挖掘：GEL

### 4.1 Pipeline

1. **元数据**：读 32 个 HF 数据集的 `meta/info.json`，确认 fps、列名、相机参数、episode 数。
2. **只读 state/action**：用 PyArrow 读 `episode_index`、`frame_index`、`observation.state.*_gripper`、`action.*_gripper`、`action.gripper_controls`；不下载视频。
3. **事件检测**：3.2 的闭合区间；记录 start/end、stall 宽度、闭合时长、释放时刻。
4. **相位/主动臂**：用事件序号、`gripper_controls` 的 trigger/squeeze、双臂事件重叠、EE 位姿（接近/运输）打标签；主动臂 = 事件更多/闭合更深/更早开始。
5. **聚合**：`(task, arm, event_order)` → 分位数/时长/事件数分布；导出 `gel_priors.json`。
6. **验证**：按 session/任务 held-out；检查 event1/event2 的 stall 覆盖、相位顺序、主动臂准确率；不把测试 episode 挖进先验。
7. **视频二次确认**：只对事件窗口（±1s）解码腕部视频，训练/验证滑移检测器；全量 169h 不强行解码。

### 4.3 结果与解释

见 1.3.1 表。三个可执行结论：

1. **先验必须条件化**：`(task, arm, event_order)` 三元组；任务级/全局阈值会误判。
2. **HangCup 必须作为负对照**：允许“空闭到 ~0”；否则 reflex 一开始就在 HangCup 上假阳性。
3. **长保持不是新事件**：右 event2 296 帧更像保持/运输，而非第二次独立闭合；状态机用“闭合沿”触发，不是“低命令持续”触发。

### 4.4 局限

- 成功数据没有失败/滑移/夹空负样本；先验是“成功时的宽度”，不是“失败的判据”。
- 空闭可能是释放、未用臂、或任务本身的正确动作（HangCup）；必须用相位/主动臂先验区分。
- 纯滑移不能靠位置单独检测；必须腕部相机二次确认。
- 事件切分对阈值/滞后敏感；不同任务需要微调；先验必须在 held-out 上验证。
- 域偏移：测试机器人/夹爪的零点/尺度/物体分布可能不同；每端口标定 + 保守 margin。

### 5.2 每端口 `SessionState`

```python
@dataclass
class SessionState:
    port: int
    episode_id: int
    step: int
    phase: str                 # APPROACH/CLOSE/HOLD/TRANSPORT/RELEASE/RECOVER
    plan: list[Action]         # VLA 30-step plan; return k at a time
    plan_cursor: int           # next index in plan
    k: int                     # fixed per submission (5 or 8)
    gripper_cal: GripperCal    # open/closed offset + scale
    gel: GelPriors             # task/arm/event priors
    reflex_state: ReflexState  # empty/contact/slip/jam counters
    last_u: Action
    last_g: tuple[float, float]
    token: str
```

`reset()` 只清本端口状态；禁止模块级可变变量；模型后端无状态。

### 5.3 `get_action` 伪代码

```python
def get_action(obs, meta):
    assert meta.token == self.token
    if obs.episode_id != self.episode_id:
        self.reset(obs.episode_id)
    # 1. 预处理：图像缩放/堆叠；EE/关节；夹爪标定
    obs_p = preprocess(obs, self.gripper_cal)
    # 2. 相位推断（FACT-VLA 规则/分类器；无学习权重时用规则）
    self.phase = infer_phase(self.phase, obs_p, self.reflex_state)
    # 3. VLA 规划（30 步计划；每次返回 k 步；共享后端，无状态）
    if self.plan is None or self.plan_cursor + self.k > len(self.plan):
        self.plan = self.backend.predict(obs_p, session_id=self.port)
        self.plan_cursor = 0
    chunk = self.plan[self.plan_cursor : self.plan_cursor + self.k]
    self.plan_cursor += self.k
    # 4. 手臂：CHUNK-SERVO 修正（最后 3 cm）
    chunk = self.servo.correct(chunk, obs_p)
    # 5. 夹爪：GEL 先验 + GRIP-REFLEX（最后 3 mm）
    chunk = self.reflex.apply(chunk, obs_p, self.phase, self.gel)
    # 6. 安全检查 + 记录
    chunk = self.safety.clip(chunk)
    self.ledger.log(obs, chunk, self.phase, self.reflex_state)
    self.step += self.k
    return {"actions": chunk, "token": self.token}
```

### 5.4 动作适配（WLA → 挑战赛）

- WLA 输出 54D（相对 EE + gripper + lower_body + base + pivot）；挑战赛 EE 模式要绝对 `left/right_ee_pose_gripper_base` [6] + `gripper` [1] + `pivot` [7]。
- 适配步骤：① 取 WLA 的左右臂相对动作；② 用当前 EE 位姿 + 相对增量合成绝对目标；③ 转到挑战赛 base 系/TCP；④ 夹爪裁剪到 [0,4.5]；⑤ `pivot` 映射/保持；⑥ 下身体保持/映射。
- 坐标系/TCP 差异必须用单任务通道标定；不要假设 WLA 的 EE 系与挑战赛 `gripper_base` 完全一致（C）。
- `pivot` 逐维语义未核实；先用“保持当前/零增量”，避免引入未知自由度（C）。

### 5.5 反射状态机

| 当前相位 | 事件 | 下一相位 | 动作 |
|---|---|---|---|
| APPROACH | EE 到位/距离阈值 | CLOSE | 开始闭爪 |
| CLOSE | `g_t` 进入先验区间 | HOLD | 保持；记录 stall |
| CLOSE | `g_t` 低于 `w_lo`（空闭） | RECOVER | 停止闭合；抬腕/重试 |
| HOLD | `g_t` 高于 `w_hi`（滑移） | HOLD | 补夹；腕部确认 |
| HOLD | `|e_t|` 大且超时（卡滞） | RECOVER | 反向微开；重试 |
| HOLD | 到达放置点 | RELEASE | 开爪 |
| RELEASE | `g_t` 跟随上升 | RECOVER | 清空相位 |
| RECOVER | 重试预算用完 | APPROACH/失败 | 交给 VLA/CHUNK-SERVO |

### 5.6 PORT-MESH 细节

- **Launcher**：`N` 从配置/环境变量读取；端口连续；失败端口自动重启；启动前检查 8765..8765+N-1 未被占用。
- **Batcher**：10–20ms 窗口；按 `session_id` 分组；单请求超时；批大小上限按显存调。
- **Calibration**：每端口夹爪开/合偏移（用 `reset()` 后的空闭/全开动作测）、腕部内参（数据已给）、头相机外参（腰部关节 + URDF）、RTT 基线；存 `calib_{port}.json`。
- **DeadlineGuard**：p99 超阈值 → 返回保持/微动；连续超时 → 降级到 N 副本/保守 k；绝不改变 metadata 的固定 k。
- **TrialLedger**：JSONL；每条记录 `port, episode, step, t_send, t_recv, latency_ms, phase, gripper_u, gripper_g, event, delta, actions_summary`；用于失败归因。
- **压测**：N=3 并发；交错 reset；人为注入 100–500ms 延迟；检查端口间状态泄漏（同一输入不同端口输出应一致；不同 session 不应互相影响）。

### 5.7 GRIP-AUX（可选）

- 在 WLA action expert 的共享特征上接 MLP：输入 `h_t` + `g_t` + `e_t`，输出 contact/stall/slip/jam 四头。
- 标签：contact = 闭合区间内 `g_t` 接近先验；stall = `min(g)`；slip = 保持段 `g_t` 上升/腕部位移；jam = `|e_t|` 大。
- 损失：`L = L_action + 0.1*L_contact + 0.1*L_stall + 0.1*L_slip`；只在有标签的帧算辅助损失。
- 推理：辅助头输出用于门控 reflex（提高/降低触发阈值），不替代动作头；仍是同一 checkpoint。
- 门槛：G2/G3 过 + G4 正收益才做；否则砍掉。

## 6. 训练与微调

### 6.1 WLA base 微调

- 默认：冻结 VLM，只训 DiT action head + robot-state projector；单卡 24GB；LoRA 可选（更省显存，但可能欠拟合执行细节）。
- 数据：32 个 HF 数据集（LeRobot 格式）；动作/状态按 WLA 54D/60D 适配；图像三路（头 + 左右腕）；`pivot`/下身体按挑战赛配置。
- 采样：官方 loader 按样本数比例；**`weight` 不生效**；要任务重加权就复制数据或改 loader。
- 验证：按任务/背景/session 分组；不要随机切帧（相邻帧泄漏）。
- 输出：一个 checkpoint（通才），不是 32 个。

### 6.2 GEN-STRAT 数据配方

- **空间优先**：物体位姿、相机位姿、桌高、初始关节、放置点；这些是 5 轴里最通用、最便宜的。
- **外观其次**：背景纹理/颜色/光照、干扰物 copy-paste、未见物品替换；用 3D 资产/生成模型，不要只加噪声。
- **人为干扰**：编辑对（目标移动/遮挡/替换）+ CHUNK-SERVO recover；训练时注入“观测过期/目标移动”的样本。
- **分层验证**：按 `(session, background, object, position)` 分组；验证集必须含未见背景/物体/位置偏移。
- **任务权重**：A 档（插/挂/叠/锁/拉链/倒）优先；但不要用预览榜单排名当权重。
- **不做**：不把成功数据当失败数据；不假设 32 任务等难度；不随机切帧。

### 6.3 辅助标签

- 从 `observation.state.*_gripper` 自动生成 contact/stall/slip/jam 标签；不需要人工标注。
- 滑移标签需要腕部视频事件窗口；先用光流/特征位移，阈值用成功数据校准。
- 标签噪声：成功数据里“空闭”是正常动作；辅助头要学“任务/相位条件”，不能学全局“空闭=失败”。

### 6.4 算力预算

| 场景 | 最低 | 推荐 | 备注 |
|---|---|---|---|
| WLA 微调 | 1×24GB | 1×40/80GB | 冻结 VLM；LoRA 更省 |
| N=1 推理 | 1×24GB | 1×40GB | 6B bf16 + 图像编码 |
| N=2 副本 | 2×24GB | 2×40GB | 最稳的端口隔离 |
| N≥3 共享 | 1×80GB | 2×80GB | 严格无状态 + 批处理 |
| GEL/reflex | CPU | CPU | 只读 state/action |
| 数据存储 | 3–10GB | 50GB | state/action；视频按需 |

## 7. 实验设计

### 7.1 离线

- **GEL 事件**：32k episodes 跑事件检测；统计每任务/臂/事件序号的 stall 分位数、事件数、时长；held-out episode 覆盖。
- **反射回放**：用成功轨迹做正例；用 HangCup 空闭/提前释放/人为注入的滑移做负例；指标：检测率、假阳性、延迟（帧）、修正幅度。
- **通过**：检测率 >80%，假阳性 <5%，延迟 ≤3 帧。

### 7.2 仿真

- 平台：MuJoCo / IsaacLab（官方 `unitree_mujoco`/`unitree_sim_isaaclab`）。
- 任务：PlugInEthernet（peg-in-hole）、HangCup（hook）、StackBowls（stack）、ZipUp（zipper）、FoldTowel（deformable，防回归）。
- 扰动：物体位置 ±2cm、夹爪零点 ±0.05、RTT 0–200ms、视觉遮挡/背景变化。
- 指标：空闭检测、滑移恢复、卡滞恢复、任务成功率、动作平滑度。
- 通过：恢复率 >70%，无安全违规，sim2real 方向一致（不要求绝对值）。

### 7.3 单任务通道

- 5 任务 ×5 trials A/B（reflex on/off）；配对同一初始条件；bootstrap 置信区间。
- 通过：≥3 任务 +10pp；HangCup 不回归；无安全违规。
- 注意：每任务 5 trials 的标准误很大；必须配对/多任务聚合，不能只看单次。

### 7.4 多端口 dry run

- N=3；并发；交错 reset；状态泄漏测试（同一 obs 不同端口输出一致；不同 session 不互相影响）。
- 指标：p50/p99 `get_action` 延迟、端口间延迟方差、显存峰值、端口重启次数。
- 通过：无跨端口状态；p99 ≤150ms（k=5 时目标）；显存稳定。

### 7.5 全量 dry run

- 32×10（或尽量接近）；端口故障注入；超时统计；ledger 归因。
- 指标：总平均成功率、步骤分、每端口方差、超时率、异常事件。
- 通过：无端口串扰；超时 <1%；ledger 可归因；可回退。

### 7.6 消融

| 消融 | 目的 | 预期 |
|---|---|---|
| reflex on/off | 夹爪反射是否涨点 | 插/挂/叠/锁任务 +；HangCup 不降 |
| GEL prior on/off | 任务/相位先验是否必要 | 去掉后假阳性上升 |
| wrist second look | 滑移二次确认是否必要 | 去掉后滑移误报上升 |
| per-port calibration | 标定是否必要 | 去掉后端口方差上升 |
| GRIP-AUX | 辅助头是否值得 | 只在 G2/G3 过后测 |
| CHUNK-SERVO on/off | 手臂伺服是否仍需要 | 保留；与 reflex 互补 |

### 7.7 实验门 G0–G8

| 门 | 问题 | 最小实验 | 通过标准 | 失败则 |
|---|---|---|---|---|
| **G0** | 数据/标定可用？ | 32 任务 `recomputed_ee_valid`、夹爪范围、腕部内参、手眼标定 | 全有效；腕部内参可用；手眼重投影 <5 px | 先修标定 |
| **G1** | GEL 先验可分？ | 32k state/action 事件挖掘；held-out | 事件覆盖；相位顺序 >80%；主动臂 >85% | 退回任务级先验 |
| **G2** | 离线反射有效？ | 成功正例 + HangCup 负例 + 注入负例 | 检测 >80%；假阳性 <5%；延迟 ≤3 帧 | 调阈值/加腕部确认 |
| **G3** | 仿真可迁移？ | MuJoCo/IsaacLab 5 任务 | 恢复 >70%；无安全违规；方向一致 | 缩小动作/只做空闭 |
| **G4** | 单任务涨点？ | 5 任务 ×5 A/B | ≥3 任务 +10pp；HangCup 不回归；显著 | 只保留空闭检测 |
| **G5** | 多端口隔离？ | N=3 并发 + 交错 reset | 无状态泄漏；p99 ≤150ms；显存稳定 | N 副本/减 batch |
| **G6** | 32×10 稳？ | 全量 dry run + 故障注入 | 无串扰；超时 <1%；ledger 可归因 | 回退保守配置 |
| **G7** | 消融成立？ | reflex/priors/wrist/calib 逐项关 | 每项有可解释边际 | 砍无贡献项 |
| **G8** | 泛化轴掉点？ | 5 轴 held-out | 任一轴 ≤10pp；平均不降 | 加数据/加恢复 |

## 8. 竞赛策略

### 8.1 任务组合

- **A 档（优先，接触密集）**：PlugInEthernet、DisconnectEthernet、HangCup、PlugCharger、Unlock、OpenPillBottle、ZipUp、StackBowls、StackCups、PaperCupStacking、ArrangeTestTubes、ToolboxStorage、OrganizeStationery、PackBag、StoreRacket、StoreEarphones、PackPhone、OrganizePencilCase、SyringeWaterTransfer。
- **B 档（搬运/分类/变形）**：FruitBasketCollection、FruitSorting、ColorArrangement、PlacePhotoFrames、OrganizeBookshelf、PickOutBattery、OrganizeTools、FoldTowel、ClearPlates、SpellRobot、ConveyorFoodSorting、RemovePinnedNote。
- **C 档（动态/长程子阶段）**：ConveyorFoodSorting 的传送带动态段、FoldTowel 的变形段、SpellRobot 的长程段；先用 VLA + CHUNK-SERVO，不强行加 reflex。
- **GEL 覆盖优先**：先挖 A 档任务的 event1/event2 宽度；HangCup 作为负对照；PlugInEthernet 作为双臂/多相位主实验；StackBowls 作为宽分布实验。

### 8.2 试次算术

- 320 trials；总平均成功率的标准误约 `sqrt(p(1-p)/320)`；p=0.3 时约 **2.6pp**。
- 单任务 10 trials 的标准误约 **14.5pp**；单任务 +10pp 不能靠一次 A/B 证明。
- 单任务通道 5 trials 的标准误约 **20pp**；必须配对/多任务聚合/看效应方向。
- 结论：reflex 的收益要用“多个接触任务的方向一致性 + 总平均”判断，不能用一个任务的单次结果。

### 8.3 提交节奏

1. **安全基线**：WLA 微调 + CHUNK-SERVO，固定 k=8，先锁一个可运行提交。
2. **单任务 A/B**：PlugInEthernet/HangCup/StackBowls 上 reflex on/off；通过 G4 后进主提交。
3. **多端口压测**：N=3 共享后端 vs N 副本；通过 G5/G6 后提交。
4. **最终**：k=5 vs 8 的 A/B；保留回滚；不要把未过门的 GRIP-AUX 放进主提交。

## 9. 风险与合规

| 风险 | 影响 | 缓解 | 合规 |
|---|---|---|---|
| 空闭假阳性（HangCup） | 任务失败 | GEL 先验；HangCup 负对照；margin | 确定性控制器 |
| 纯滑移检测不到 | 掉物 | 腕部相机二次确认；不单独靠位置 | 不是第二模型 |
| API 夹爪语义不明 | 反射方向错 | 单任务通道标定；先用保守阈值 | 无 |
| 标定漂移 | 端口间方差 | 每端口 reset 后检查；标定 JSON | 无 |
| 共享后端状态泄漏 | 跨端口污染 | 无状态推理；session_id；压测 | 无 |
| p99 延迟尖峰 | chunk 超时 | DeadlineGuard；N 副本；保守 k | 不改固定 k |
| 单模型规则 | 取消资格 | reflex/GEL/PORT-MESH 非学习模型；GRIP-AUX 同 checkpoint | 有疑问不启用 |
| 数据泄漏 | 过拟合 | 按 session/任务 held-out；不挖测试 episode | 无 |
| 评估噪声 | 误判收益 | 配对/多任务/置信区间 | 无 |
| 时间不足 | 做不完 | 先 G0–G2；G4 不过砍 GRIP-AUX | 无 |
