# 第 44 轮（新循环第 1 轮） · Retrieval-Cert × Roadmap-Cert：把「检索增强生成」与「技术路线图」纳入可验证证据闭环（四层架构 v9）

> 承接第 43 轮 v20（Persona-Cert × Concurrent-Cert）。v20 自陈最大风险是「共形边际覆盖 + 多用户契约空集」，但它与此前所有版本一样，仍压着两个未言明的单点假设：**(H3)「检索」被当成确定性查表**——CKB 一查即得、证据天然可信，忽略了检索是**随机、多源、可被污染、会过期**的证据行动，证书链因此可能在「查到了但查错了/查旧了/被投毒了」处静默断裂；**(H4)「技术路线图」被当成叙事 PPT**——能力声明按灵感不断累加，却不与实验、证据、回退绑定，使 IP 越多、论文工件越精致，整个研究程序反而越不可证伪。本轮灵感词「检索增强生成」「技术路线图」精确命中这两个假设：**RAG** 迫使我们把检索从「取数」升级为**可签发、可弃答、可反事实检验的证据行动**；**技术路线图**迫使我们把「要做什么、凭什么说做到了」升级为**可执行的程序证书**。二者耦合处才是本轮真正的新问题：路线图的能力声明要由 RAG 证据来「链接」，而 RAG 证据本身不确定、会过期、可被对抗——于是「程序级 soundness」第一次与「检索级 soundness」纠缠在一起。

## 0. 直觉与动机

**灵感 1（RAG → 检索不是查表，而是「带溯源的证据行动」）**：直觉上，系统回答「这个区域能不能进」时，不是从知识库里捞一段文本就信，而是像法庭采信证物一样追问：**谁给的？什么时候测的？适用于这个任务吗？许可是什么？有没有可能被人塞了假证物？** 因此每条证据必须携带**溯源类型**（测量/证书/规范/人类报告/模型输出/地图几何）与 Merkle 溯源链，检索结果必须形成一张**检索证书** R_q：它能说明「哪些证据支撑这句话、支撑是否充分、换掉/污染若干条后结论是否仍然成立」，否则就**弃答（abstain）**而不是硬答。关键原则是 **no-evidence-no-decision**：凡是会进入守卫的检索结论，没有 sound 的检索证书就只允许单调降级或安全停机。RAG 由此从「生成的一句漂亮话」变成「可审计的证据包」。

**灵感 2（技术路线图 → 路线图不是 PPT，而是「程序证书 / 研究类型系统」）**：直觉上，一份可信的路线图应当像编译器：每个节点是一次**能力声明**，每条边是**证据依赖**，节点能不能从「计划」变成「已达成」，取决于它的证据是否**类型检查通过**——声明强度不得超过证据强度，缺证据就是类型错误，循环自证就是非法引用，关键路径上没有回退就是未处理的异常。于是路线图成为可执行的 **G = (N, E)**：每个节点自带验收实验（E-gate）、证据谓词、杀伤判据（kill criterion）、回退与截止期；只有证据证书齐备的节点才能被标记 accepted。一句话：**路线图不是描述未来，而是约束「此刻允许声称什么」。**

**灵感 3（耦合 → 双时钟、证据独立性与能力悬崖）**：RAG 与路线图耦合后出现三个新失效模式：**(a) 时钟耦合**——路线图按周/月推进，安全监控按毫秒运行，若慢环的「路线图更新」能直接改控制阈值，安全地板就被悄悄侵蚀；**(b) 循环自证**——同一个模型既生成能力声明又生成支撑它的证据，审计看起来全绿，实则自我指涉；**(c) 能力悬崖**——某个关键里程碑只靠一条未复现的证据节点支撑、且无回退路径，一旦该证据被推翻，整个能力声明塌方。对策分别是：**双时钟 + 安全地板单调性**（慢环只能提 proposal，永不直接写控制回路）；**证据独立性约束**（证据生成者与声明者必须可分离、可独立重放）；**证据不确定性下的鲁棒可达性**（把证据置信度沿 DAG 传播，显式标出能力悬崖并强制回退）。三者共同保证：v9 不只是「给 v8 加一个知识库」，而是给整个研究程序装上**可证伪的脊柱**。

**耦合升级**：CRE（认证检索引擎）把 CKB 从「文本库」升级为「溯源类型化证据库 + 检索证书」；RCP（路线图证书编译器）把研究计划编译成带 E-gate、能力债务与安全地板的 DAG；PEA（程序证据审计器）独立审计「路线图声明 ↔ 检索证据 ↔ 历史版本」，并把反例回灌 SCV/CKB。四层架构由 v8 的「仿真-检索-边缘飞轮 + 人格 + 并发」升级为 v9 的「同一实时安全平面 + 一个**永不进入控制回路**的证据/程序平面」。

## 1. 形式化定义（增量：定义 44–49）

**定义 44（溯源类型化证据与检索证书）**：证据原子 d=(κ, a, src, π, τ_d, TTL, scope, lic, risk)：κ∈{measurement, certificate, spec, human-report, model-output, map-geo} 为证据类型，a 为断言，src 为来源，π 为可验证的溯源链（Merkle DAG，根为信任锚），τ_d 为测量时刻，TTL 为有效期，scope 为适用域（任务×人格×环境），lic 为使用许可，risk 为对抗风险级。查询 q=(need, scope_q, deadline, k, m_poison)。检索器返回 S=TopK(q)，**可采信集** S⁺={d∈S : t≤τ_d+TTL ∧ scope_q⊆scope ∧ lic_permits ∧ verify(π)=1 ∧ risk≤risk_max(q)}。**检索证书** R_q=(S⁺, α, ρ, abstain, coverage, epoch)：α 把每条生成断言映射到支撑子集 S_c⊆S⁺，并要求 V(S_c)⊨claim（V 为蕴含/校验器）；ρ 为反事实鲁棒裕度（定义 45）；epoch 为索引版本。**sound 性**：R_q sound ⇔ abstain=true（不产生任何决策），或所有断言均被 α 归因到可采信支撑、溯源根可信、且 ρ-鲁棒。**不变式（no-evidence-no-decision）**：任何依赖检索的守卫更新，必须携带 abstain=false ∧ sound 的 R_q；否则只能单调降级或安全停机。**命题**：若每条被采用断言都有可采信支撑且溯源链可验，则「检索幻觉」不可能以「支撑充分」的外观进入守卫——它最多以弃答出现。

**定义 45（反事实检索鲁棒性与投毒预算）**：扰动族 P_{m,δ} 包含：删除任一来源类、注入至多 m 条投毒原子、在 δ 内改写内容、切换到陈旧版本。记 A_R(S) 为从证据集 S 导出的证书/答案。称 R_q 在 P_{m,δ} 下 **ρ-鲁棒**，若 ∀S′∈P_{m,δ}(S)：A_R(S′) 或为弃答，或其证书集合包含于 A_R(S)。**投毒预算** m 是对手能力的显式假设，必须被监控与红队挑战，而不能默认成立。**命题**：若 R_q 对 P_{m,δ} ρ-鲁棒，且实际对手注入 ≤m，则单源投毒无法翻转任何已认证的守卫决策（只能触发弃答）。**推论**：把「鲁棒性预算」写进证书，比笼统宣称「我们做了 RAG 安全」更可审计，也更可被推翻。

**定义 46（可执行技术路线图与路线图证书）**：路线图 G=(N,E) 为能力 DAG，节点 n=(claim_n, TRL_n, E_req_n, deps_n, fallback_n, deadline_n, owner_n, evidence_hash_n)。E_req_n 是定义在「检索证书 ∪ 实验证书」上的证据谓词；fallback_n 是节点失败时的替代能力路径。节点状态 state(n)∈{hypothesis, planned, in_progress, evidenced, accepted, retired}，**唯一合法升级**：evidenced→accepted 当且仅当 E_req_n 被可复现证书满足 ∧ deps_n 均 accepted ∧ fallback_n 存在 ∧ independence(evidence_n, claimant_n) ∧ safety_floor(G) 保持。**能力债务** D(G)=Σ_n w_n·debt(n)，其中 accepted 却无证据记 1、关键路径无回退记 0.5、证据陈旧记 0.3。**路线图 sound** ⇔ 所有 accepted 节点均有证据支撑且无超额声明。**安全地板不变式**：∀ 版本 v，G_v 必须保留 v8 的「安全监控 + 安全停机 + 纯收缩个性化」基线能力。

**定义 47（证据不确定性下的能力可达性与能力悬崖）**：每个节点带证据置信 c_n∈[0,1]（由检索覆盖 × 反事实鲁棒 × 独立重放共同给出）。对失败集 F（|F|≤ρ，或按分布采样），里程碑 m 的 **ρ-鲁棒可达性** 为 R_ρ(m)=min_{F:|F|≤ρ} reach(m, G∖F)，其中 reach 允许走 fallback 边。**能力悬崖**：若 R_ρ(m) < γ 或 m 的关键路径上存在无 fallback 的未复现证据节点，则称 m 处于能力悬崖。**命题**：路线图的鲁棒性不可能高于「关键路径上证据置信 × 回退覆盖率」的最小值；截止期压力只能改变计划，不能改变证据。**推论**：把能力悬崖显式画出来，比在 PPT 上把里程碑涂成绿色诚实得多。

**定义 48（路线图-证据一致性与无断言原则）**：令声明强度 s_c=(TRL, scope, effect, population, environment)，证据强度 s_e 同构。**超额声明（overclaim）**：s_c 不在各分量上 ≤ s_e。**审计违规** Audit(G,E) 包含 {uncited（无引用）, stale（证据过期）, overclaim, circular（声明者出现在其证据的溯源链中）, conflict（支撑集互相矛盾）, orphan（依赖已退役节点）}。**无断言原则**：accepted 节点的声明强度不得超过证据强度。**命题**：若 Audit(G,E)=∅ 且所有检索证书 sound，则路线图声称的能力集合 ⊆ 系统实际被认证的能力集合。**注**：这条命题把「论文/路线图声明」第一次纳入可证伪范围，而不是留给评审的善意。

**定义 49（双时钟隔离与安全地板单调性）**：快时钟 T_f（毫秒）是唯一可写控制回路、可修改守卫阈值、可触发停机的平面；慢时钟 T_s（周/月）承载检索索引、证据、路线图。慢环更新 u:G→G′ 合法，当且仅当：(i) safety_floor(G′)⊇safety_floor(G)（只增不减）；(ii) u 不写任何控制守卫/阈值；(iii) 每个新 accepted 节点有证据与回退；(iv) u 的 diff 通过 PEA 审计。慢环只能发出 **proposal**（能力声明、配置建议），proposal 要影响行为必须再过快环的证书门。**定理（双时钟安全）**：若初始控制不变式 I 成立、慢环更新只改声明/证据/计划而不改安全谓词与阈值，则快慢任意交错都保持 I；且慢环的任何「降级/退役」只能收紧而非放宽可行域。**推论**：路线图再激进，也不能把安全地板当筹码；它最多让程序更早承认某能力未达成。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-60 CERTIFIED-RETRIEVAL-ENGINE（认证检索引擎 CRE）
1. **溯源类型化证据库**：每条证据带类型、来源、Merkle 溯源链、TTL、scope、license、对抗风险；索引按证据 epoch 版本化，禁止跨 epoch 混检。
2. **检索证书生成**：TopK → 可采信过滤 → 断言归因（α）→ 蕴含校验（V）→ 反事实鲁棒检查 → 签发 R_q 或 abstain。
3. **数据/控制分离与注入防御**：检索文本永远是「数据」而非「指令」；工具调用必须经 schema + scope + 人工/证书门；指令层级与来源白名单共同阻断 prompt injection。
4. **证据新鲜度租约**：每条证据携带 (m_e, τ, λ, epoch)，与 IP-58 的证书租约同构；过期即触发重检索或单调降级，绝不把陈旧证据当新鲜。
5. **冲突消解与弃答**：多源冲突时按类型优先级（certificate > measurement > human-report > model-output）与独立性投票；无法消解则返回认证先验或安全停机。

### 2.2 IP-61 ROADMAP-CERT-COMPILER（路线图证书编译器 RCP）
1. **路线图 DSL → 能力 DAG**：把 claim/TRL/E_req/deps/fallback/deadline/owner 编译为可检查的图；每个节点必须有杀伤判据（什么结果会推翻它）。
2. **E-gate 编译**：每个节点映射到验收实验（E95–E102 及后续）与证据谓词，实验未过则节点不得 accepted。
3. **能力债务 + 安全地板**：维护能力债务账本；任何更新先检查安全地板单调性；关键路径缺回退直接标红。
4. **证据不确定性传播**：计算 ρ-鲁棒可达性、能力悬崖、回退覆盖率；截止期只影响排序，不影响证据门槛。
5. **版本化与证据钉扎**：每个 accepted 节点钉住证据哈希与独立重放结果；路线图有 epoch，diff 必须附证据增量。

### 2.3 IP-62 PROGRAM-EVIDENCE-AUDITOR（程序证据审计器 PEA）
1. **路线图-证据审计**：检出 uncited / stale / overclaim / circular / conflict / orphan，把审计结果作为 accepted 的必要条件。
2. **对抗检索与对抗路线图**：投毒文档、陈旧索引、冲突来源、scope creep、截止期压力下的「先声明后补证」。
3. **独立重放**：对 accepted 节点的证据做独立管线重跑，检查可复现性与溯源独立性，拒绝自证。
4. **漂移监控**：来源分布漂移、索引陈旧度、能力回归；一旦漂移超阈值，冻结相关节点的 accepted 状态。
5. **反例回灌**：把检索/路线图反例回灌 SCV 与 CKB，进入下一轮课程与压力测试。

## 3. 四层架构 v9

```
【快时钟 T_f（毫秒，唯一可写控制回路）】
L1: TRI-FUSE(INT8) + IP-49 LIO → C_ms + B_t + L_m
    地图/几何证据带 TTL → 过期即降级（IP-60 evidence lease）
L2: CTC + VLM + IP-35 仲裁 → R_φ(w) 分支池
    VLM 生成必须绑定检索证书 R_q（IP-60），否则 abstain
L3: IP-51 CAR(+RetrievalMode/EvidenceEpoch/RoadmapEpoch)
    ← IP-58 CCR(租约表 + RG 守卫 + 混合关键级)
    → IP-53 CMC(阈值绑定证据证书版本)
    → IP-45 总线(retrieval/evidence/roadmap/audit)
L4: IP-57 PCE + IP-55 CKB(溯源类型化证据库 + 版本化索引)
    ← IP-59 ICV(交错 + 检索对抗)
    ← IP-54 SCV(投毒/陈旧/节点失败仿真)

【慢时钟 T_s（周/月，永不进入控制回路，只能提 proposal）】
E1: IP-60 CRE —— 检索证书 / 反事实鲁棒 / 弃答 / 证据租约
E2: IP-61 RCP —— 路线图 DAG / E-gate / 能力债务 / 安全地板 / 能力悬崖
E3: IP-62 PEA —— 审计 / 独立重放 / 对抗 / 漂移
    慢环 proposal 必须经快环证书门才能影响行为；证据/路线图/证书 epoch 单调对账
    安全地板：v8 的监控 + 安全停机 + 纯收缩个性化永远保留
```

**双时钟为什么是结构性的而非工程约定**：v20 已经把安全监控、租约、混合关键级做成毫秒级快环；本轮若把「路线图目标」直接塞进快环，就会出现「为了赶里程碑而放宽阈值」的经典腐败路径。v9 因此把「声明/计划」与「执行/守卫」在**权限**上分开：慢环可以更激进地规划，但它的任何结论都只是 proposal；能改行为的只有快环里带检索证书与实验证书的证书门。

## 4. 实验设计（E95–E102 硬门槛，承接 E87–E94）

### IP-60 CRE：证据可采信、检索证书与反事实鲁棒
```
def admissible(d, q, t):
    return (t <= d.tau + d.ttl
            and q.scope.subset_of(d.scope)
            and d.lic.permits(q.purpose)
            and verify_merkle(d.pi, roots=TRUST_ANCHORS)
            and d.risk <= q.risk_max)

def build_retrieval_certificate(q, t):
    S = retriever.topk(q)
    S_plus = [d for d in S if admissible(d, q, t)]
    if not S_plus:
        return RetrievalCert(S_plus, abstain=True, reason="no_admissible")
    claims = generate(q, S_plus)              # 生成只允许读可采信集
    attrib = {}
    for c in claims:
        sup = V.support(c, S_plus)            # 蕴含/校验器找最小支撑子集
        if sup is None:
            return RetrievalCert(S_plus, abstain=True, reason="unsupported")
        attrib[c] = sup
    rho = counterfactual_margin(q, S_plus, q.m_poison, q.delta)
    if rho < 1.0:
        return RetrievalCert(S_plus, abstain=True, reason="not_robust")
    return RetrievalCert(S_plus, attrib, rho=rho, abstain=False,
                         epoch=index.epoch)

def counterfactual_margin(q, S, m, delta):
    base = derive(S, q)
    for S2 in perturbation_family(S, m, delta):
        a2 = derive(S2, q)
        if a2 is not ABSTAIN and not subset(a2.certified, base.certified):
            return 0.0
    return 1.0

def evidence_lease(d):
    return Lease(m=d.strength, tau=d.tau, lam=d.lam, epoch=d.epoch)

def evidence_valid(d, need, t):
    return (d.epoch == index.epoch
            and d.m - d.lam * (t - d.tau) >= need)
```

def compile_node(spec):

def accept_node(n, G, E, t):
    if not e_req_satisfied(n.e_req, E, t): return False
    if not all(G[d].state == ACCEPTED for d in n.deps): return False
    if n.fallback is None and on_critical_path(n, G): return False
    if not independent(n.evidence, n.claim): return False       # 防循环自证
    if not safety_floor_preserved(G, add=n): return False
    if audit_node(n, E, t): return False
    n.state = ACCEPTED; n.evidence_hash = hash_evidence(n, E, t)
    return True

def capability_reach(G, milestone, rho):
    return min(reach(G, milestone, forbid=F)
               for F in failure_sets(G, rho))

def capability_cliff(G, milestone, rho, gamma):
    if capability_reach(G, milestone, rho) < gamma: return True
    return any(no_fallback(n) and not reproduced(n)
               for n in critical_path(G, milestone))

### IP-62 PEA：审计、独立重放与双时钟门
```
def audit_node(n, E, t):
    v = set()
    ev = E.get(n.claim, [])
    if not ev: v.add("uncited")
    for e in ev:
        if n.claim.issuer in e.pi.issuers: v.add("circular")
        if e.epoch != index.epoch or not evidence_valid(e, n.need, t):
            v.add("stale")
        if not strength_leq(n.claim.strength, e.strength): v.add("overclaim")
        if contradicts(ev): v.add("conflict")
    if any(G[d].state == RETIRED for d in n.deps): v.add("orphan")
    return v

def independent_replay(n, E, replay_pipeline):
    # 必须由与声明者不同的管线/团队重跑，否则拒绝
    if replay_pipeline.signers & E[n.claim].signers:
        return ReplayResult(ok=False, reason="not_independent")
    return replay_pipeline.reproduce(n.e_req, tolerance=EPS_REP)

def slow_loop_update(G, proposal):
    G2 = apply(G, proposal)
    if not safety_floor_preserved(G, G2): return reject("safety_floor")
    if writes_control_thresholds(proposal): return reject("control_write")
    if any(not node_has_evidence(n, G2) for n in G2.changed):
        return reject("missing_evidence")
    if PEA.audit(G2) != set(): return reject("audit")
    if not all(independent_replay(n, E, rp) for n in G2.changed):
        return reject("not_independent")
    return commit_versioned(G2)          # 只改声明/计划，不影响快环

def apply_proposal_to_control(p, cert_gate):
    # 慢环 proposal 只有在快环证书门下才可能影响行为
    return cert_gate.admit(p)            # 需 retrieval cert + experiment cert + safety floor
```

def car_guard_v9(e, x, cert_obj, persona, lease, rcert, t):
    theta = cert_obj.alpha_e[e] * cert_obj.theta_sim[e]
    m_lookup = cert_lookup_L0(x).m_lo[e]

| 路线图被 deadline 压力 Goodhart 化 | 高 | 杀伤判据 + 独立审计 + 安全地板硬约束；E99/E102 红线；慢性失败即熔断 |
| 慢环更新意外渗入控制回路 | 高 | 权限隔离 + 运行时守卫 + proposal 证书门；E99 红线；写控制即拒绝 |
| 索引漂移/来源分布漂移使 TTL 失效 | 中 | 漂移监控 + 冻结索引版本 + 缩短 TTL；E98 红线 |
| 能力悬崖被乐观置信掩盖 | 中-高 | 显式 R_ρ 下界 + 关键路径强制 fallback；E100/E101 红线 |
| 超额声明逐轮 creep（IP/论文压力） | 中-高 | 声明/证据强度分量格 + 类型检查 + PEA 审计；E99 红线 |
| 弃答率过高导致可用性崩塌 | 中 | 检索质量/索引覆盖作为一等指标；关键场景预取 + 静态认证表兜底；E95 校准弃答率 |

## 7. 本轮最大风险

**一句话**：检索证书的 soundness 依赖「信任锚 + 有界投毒预算」这些外部假设，路线图证书的 soundness 依赖「证据与声明相互独立」；一旦在截止期压力下由同一模型既生成能力声明又生成支撑证据（循环自证），v21 就会产出一个审计全绿、却认识论上自我指涉的研究程序——因此 E99（循环自证/超额声明）与 E102（独立重放/长时程回归）必须设为红线，且默认回退到「静态认证表 + v8 安全地板」这条不依赖检索的底线。
