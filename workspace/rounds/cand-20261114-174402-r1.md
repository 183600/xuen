# 第 70 轮（承接第 69 轮「FLUID-RAS」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「语言指令」×「时空推理」）

> R69 已经会「问」，但它问的是**动作层面的歧义**（走左还是走右），并默认「要做什么」这个目标本身是清楚的。语言指令打破了这个默认：人说「把杯子放到桌上，别碰倒左边那个花瓶，等我数到三再松手」——这里有指代歧义（哪个杯子、谁的左边）、有时序承诺（等数到三）、有持续约束（松手前都不能碰倒）、还有默认值（「桌上」具体哪个位置）。R69 的 VoI 会去消解「怎么走」，却不会去消解「你到底要我做什么」；更危险的是，它可能**高效且安全地完成了错误的任务**，还附上一张形式合法的证书。
>
> 本轮两个灵感各补一半：
> - **语言指令**把任务从「一个已知目标」变成「一段必须被编译成可执行约束的规范」；
> - **时空推理**给这段规范一个可监控、可验证、可随时间和视角更新的语义（STL + 视角索引的空间关系图 + 承诺生命周期）。
>
> 核心命题：**指令不应被编译成单一程序，而应被编译成一个「解释集」（interpretation hull）；在解释集收敛前，系统只在所有合理解释的交集内行动（交集盾），用带时间贴现的 VoI 去问/看/等，并把每个解释的生命周期记成时空承诺台账。** 命名 **LATCH-RAS**（Language-Anchored Temporal-spatiotemporal Contract Hull）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**这句话到底要我做什么、从谁的视角、在什么时候**」——安全不只是做得对，还是**理解得对**。

## 0. 直觉与动机

**灵感 1（语言指令 → 目标是欠定的，不是给定的）**
直觉：R69 的整台不确定性机器都建立在「目标函数 J 已知」之上；语言指令恰恰让 J 本身带不确定性。同一句话可以对应多个可执行契约：paraphrase、指代、量词、默认值、言外之意。人处理这种欠定靠的是**共享上下文 + 保守默认 + 必要时澄清**，而不是赌一个最可能的 parse。所以 R70 的第一性改变：把自然语言指令编译为**候选契约集合 ℋ**，并把「解释」本身提升为一等的不确定性来源——它不能被更多的动作采样消解。

**灵感 2（时空推理 → 语义必须锚定在时空里）**
直觉：「左」「这里」「马上」「之后」「一直」都是**索引词**：离开说话人视角、离开时间戳就没有意义。R69 的状态里没有显式的「谁的左」「哪个时刻的马上」。时空推理给两件事：(a) 视角索引的空间关系图（机器人/说话人/相机坐标系与时刻）；(b) 用 STL/时序逻辑表达的时段约束与承诺生命周期（before/after/until/while/every）。于是「别碰倒花瓶」不是一句形容词，而是 `Always(¬collision(vase))` 的连续约束；「等我数到三」是一条 dormant obligation，触发前不占用动作，触发后立即变为 active。

**灵感 3（解释集 → 交集盾，安全性不再依赖「猜对语义」）**
直觉：与其先猜一个解释再验证，不如维护所有合理解释，只执行**在所有解释下都安全**的动作。这借用 robust control / distributionally robust optimization 的姿态：不对「真实解释是哪一个」下注，而是对解释集取交集。好处是安全性证明与语义猜测解耦：只要真实解释落在 ℋ 内，交集盾就保证不违反它。代价是保守（交集可能为空或很小）；而**澄清的价值恰好等于交集扩大的幅度**——这就把 R69 的 VoI 从「动作模态」推广到「解释集合」，也让「问什么」有了行为学判据。

**灵感 4（时间性 VoI → 「等」是一种带截止期风险的信息动作）**
直觉：R69 把「等」列为信息动作，却没给它时间语义。现实中很多歧义会**免费自解**：人走近了、遮挡移开了、对方自己先动手了。此时最优策略可能是「先保持安全不变量，等 Δt 再决定」，而不是急着问。但等待有截止期风险：等过头就错过任务窗口。于是 VoI 必须带时间贴现与截止期约束：`VoI_t(g) − c(g) − λ_d·P(miss deadline|g)`。这把「何时问、何时看、何时等」统一成一个时序决策问题，也正好是「时空推理」的第二层含义——不仅推理世界的时间，也推理**自己决策的时间**。

**灵感 5（语言是新攻击面 → 权限单调性优先于语义分类器）**
直觉：一旦系统读语言，就有了 prompt injection、环境文字注入、第三方语音指令、指代欺骗、时钟欺骗。R69 的投毒是「回答在骗你」；R70 的投毒是「**指令本身**在骗你」。关键防御不是再训一个语义分类器去识别恶意话术（永远有分布外），而是**权限单调性**：低权限来源的指令只能收紧安全约束、不能放松；任何试图削弱安全不变量的指令在准入控制层就被拒绝。这样注入最多造成「过度约束 / 可用性下降」，不能造成「安全下降」。

**灵感 6（承诺台账 → 禁止「重新解释掉」违规）**
直觉：如果系统可以随时改解释，它就能把一次违反「解释掉」——这与 R68 缓变故障被标定吸收是同构的失败模式，只是从传感器层搬到了语义层。所以解释更新必须有纪律：承诺是 latching 的，违反一旦发生就留痕；解释只允许在显式 replan 边界切换，且切换后必须对全部 active 承诺重新认证。这把 R69 的「证据纪律」升级为「**语义纪律**」。

## 1. 形式化定义（增量：定义 310–326）

**定义 310（LATCH-RAS 总览）** LATCH-RAS = (L2C, STG, HULL, CHRONO, SCOPE, TRC, RAS-WM†)。四不变式：
(i) **实时流零学习写操作**（继承 R69 定义 293-i / R68 定义 276-i）；
(ii) **无认证解释不执行**：任一任务动作必须属于当前解释集的鲁棒安全集 A_safe(ℋ)，或系统安全停机；
(iii) **时空锚定**：所有指代必须绑定到带时间戳的视角坐标系；无法锚定的指代视为未消解歧义；
(iv) **语义纪律**：解释切换只在 replan 边界；承诺 latching；低权限指令不得放松安全约束。

**定义 311（指令语义对象与解释集）** 指令 u（可含多句与多模态指向）经 L2C 编译为候选契约集合 C(u) = {c_1,…,c_n}，每个 c_i = (φ_i, π_i, D_i, τ_i, presup_i, defaults_i, span_i, prov_i)。解释集 ℋ_t ⊆ C(u) 为在观测 o_t、对话历史与权限约束下仍存活的候选。与 R69 的模态集 {m_k} 的关键区别：模态集是「同一目标的多种实现」，ℋ 是「不同目标/约束的多种读法」——前者可由采样消解，后者只能由语言、空间或时间证据消解。

**定义 312（视角索引的时空接地图 STG）** STG_t = (V, E_spat, E_temp, γ_t)。V 为对象/地点/事件节点；E_spat 边标注空间关系 r ∈ {left-of, right-of, on, under, near, behind, inside} 及其参考系 f ∈ {robot, speaker, camera(k)}；E_temp 边标注 before/after/during/until/every 及时刻锚点。γ_t 把指代表达（「那个」「左边」「现在」「马上」）映射到 V 或时刻，每个映射带置信度与时间戳。**视角是显式参数**：同一符号 "left" 在 robot 系与 speaker 系下可以是相反区域。

**定义 313（时空契约）** 契约 c = (φ, π, D, τ)。φ 为 STL 公式，原子命题来自 STG 的信号/事件（位置、接触、距离、事件触发）；π 为空间约束（区域隶属或关系保持，用 SDF 表达）；D 为截止期/有效窗口；τ 为鲁棒裕度。语义：轨迹 ξ 满足 c 当且仅当 ρ_c(ξ) ≥ τ，其中 ρ_c 为归一化 STL 鲁棒度与空间 SDF 裕度的最小值。算子映射：before/after → Until/Since，while/until → 区间 Always，every time → 周期触发，「数到三」→ 离散事件锚点。

**定义 314（时空鲁棒度与在线监控）** ρ_c(ξ_t) 为轨迹前缀的 dense robustness；ρ<0 即违反。监控器是 **latching** 的：一旦 ρ 在某时刻跌破 0，违反状态保持，不因后续轨迹离开而清除。鲁棒度既是安全信号，也可作为流策略的条件/引导项（CHRONO→FMP 的负梯度引导），从而把语言约束变成可微的生成引导，而不是事后过滤。

**定义 315（三重不确定性分解）** U_total = (U_ale, U_epi, U_intent)。U_ale、U_epi 继承 R69（执行噪声、动作模态歧义）；U_intent 为解释不确定性，由三项刻画：
- 语义熵 H(ℋ) = −Σ_i w_i log w_i，w_i 为候选契约后验；
- 行为散度 D_ℋ = max_{c,c'∈ℋ} max_a |J_c(a) − J_{c'}(a)|，即不同读法导致的最优行为差；
- 不可调和性 κ(ℋ) = 1[A_safe(ℋ) = ∅]。
关键：**U_intent 不能靠增加动作采样消解**（R69 的 K 采样对它无效），只能靠语言澄清、空间探查、时间等待或外部证据消解。这是 R70 与 R69 的本质分工。

**定义 316（解释鲁棒安全集 HULL）** 对解释集 ℋ，定义 A_safe(ℋ) = { a ∈ 𝒜_+ : ∀c∈ℋ, ρ_c(a) ≥ τ_c 且 a 通过 C-RAS-WM 认证 }。HULL 策略：π_H(o_t) = argmax_{a∈A_safe(ℋ)} E_{c~w}[J_c(a)]，若 A_safe 非空；否则不执行任务动作。注意：交集是在**约束**上取交集，而不是在效用上取平均——效用可以平均，安全不能平均。

**定义 317（时空澄清调度 SCOPE 与时间性 VoI）** 信息动作扩展为 g = (g_ask, g_look, g_wait)。时间性 VoI：
VoI_t(g) = E_{y~p(·|g,o_t)}[U(ℋ_{t+Δ(g)})] − U(ℋ_t) − λ_d·P(miss deadline | g, o_t)，
其中 U(ℋ) 可用 −D_ℋ 或 −H(ℋ)；λ_d 为截止期价格。选择 g* = argmax_g [VoI_t(g) − c(g)]，s.t. 安全、预算、截止期概率 ≥ 1−ε_t。若最优为 g_wait：进入 **guarded wait**（保持当前安全不变量、持续监控 ρ、不新增任务动作），并设置最大等待窗口。

**定义 318（行为性信息增益 BIG）** 对候选问题 q：BIG(q) = E[D_ℋ − D_{ℋ|answer}]，即以「行为散度的下降」而非「语义熵的下降」衡量提问价值。选择 q* = argmax BIG(q)/c(q)，且要求 BIG(q) ≥ δ_BIG，否则不问。系：BIG 把「澄清」从「问清楚这句话」收紧为「**问清楚会改变动作的那一点**」——这正是对 R69「追问幻影」的正面修补：语义上很确定但行为上无关的区分，不值得一次交互。

**定义 319（时空承诺台账 CHRONO）** 台账 L 记录每个契约的生命周期 proposed→active→dormant→discharged/violated/expired。条件承诺（after/until/while）在触发前为 dormant；触发后变为 active。解释更新时：
- 已 violated 的承诺保持（latching），不得因换解释而清除；
- 未触发的 dormant 承诺随解释更新重绑定；
- 任何「删除仍活动承诺」的操作必须由更高权限或显式澄清授权。
语义纪律：解释切换仅允许在 replan 边界 t∈B，切换后必须对全部 active 承诺重新认证。

**定义 320（截止期时空风险 TRC）** 对每个含截止期的契约 c，用流策略的 K 个轨迹样本估计 P_sat(c) = P(ρ_c(ξ_{t:t+D}) ≥ τ)。时空风险 R_t = max_{c∈active}(1 − P_sat(c))。动作要求 R_t ≤ ε_t。给出**时间松弛** slack_c = D_c − E[完成时刻]，并要求 slack_c ≥ 反应延迟 + 认证延迟。TRC 把「来得及吗」变成可审计的概率量，而不是事后追悔。

**定义 321（指令来源与权限单调性 PROV）** 指令来源 prov = (issuer, channel, time, place, auth_level)。准入控制：c 可进入 ℋ 当且仅当 prov 通过认证且 c ∧ SafetyInvariants 可满足。**权限单调性**：若 auth(prov') < auth(prov)，则 prov' 只能添加/收紧约束，不能删除/放松约束。形式化：ℋ' 加入低权限指令后，A_safe(ℋ') ⊆ A_safe(ℋ)。因此注入不能扩大可行动集合。

**定义 322（指令注入与时空欺骗干扰集 ℰ_lang）** 环境文字/屏幕/第三方语音注入、以指代为载体的诱导（把危险物指向为「那个」）、时钟/时间戳欺骗、镜面/反光/移动标签造成的空间指代欺骗、澄清钓鱼（恶意回答）、歧义养殖（故意含糊以诱发不安全默认）、范围蔓延（逐步扩大授权）。ℰ_LATCH = ℰ_FLUID × ℰ_lang。

**定义 323（默认值与最小承诺）** 对欠定表达，L2C 给出**带标记的保守默认**（区间而非点，且默认取使 A_safe 最大化的保守值），并记录 default_source。原则：**最小承诺**——除非行为散度为零，否则不把「最可能的读法」当作唯一读法；默认只用于缩小搜索，不用于跳过认证。

**定义 324（在线重编译与解释稳定性）** 新证据 y 到达后，ℋ_{t+} = ℋ_t ∩ {c : c 与 y 相容}（若为空则视为冲突并升级）。为避免解释抖动（chattering），引入**解释稳定性**：在一个决策 epoch 内不切换契约，除非 κ(ℋ)=1 或 R_t > ε_t；切换必须走 replan 边界并重认证。此定义保证控制连续（呼应 R69 定理 17）。

**定义 325（证书 J_LATCH）** J_LATCH = (J_FLUID, hull_cardinality, semantic_entropy, behavioral_divergence, hull_completeness_audit, temporal_sat_p95, spatial_grounding_conf, commitment_ledger_hash, provenance_root, latching_ver)。Valid ⇔ Valid(J_FLUID) ∧ (|ℋ|=1 或 执行动作∈A_safe(ℋ)) ∧ R_t ≤ ε_t ∧ 权限认证通过 ∧ 语义纪律未破。

**定义 326（两级退避的扩展：意图层 + 动作层）** 继承 R69 定义 307 的动作层两级退避，并在其上增加**意图层**：
- ℋ 可收敛（澄清/证据充分）→ 按收敛契约执行，获得 *intent bonus*（比交集盾更不保守）；
- ℋ 未收敛但 A_safe(ℋ) ≠ ∅ → 交集盾内执行（robust interpretation bonus）；
- A_safe(ℋ)=∅ 或冲突不可调和 → 不执行任务动作，安全停机 + 升级（最保守）。
当 |ℋ|=1 时退化为 R69 FLUID-RAS；当再满足 VoI≤c 时退化为 R68。⇒ **R69 是 R70 在「单解释」边界上的严格退化**。

```python
# IP-264 L2C：指令 -> 候选契约集合（缓存模板 + 约束解码；不占控制环）
def compile_instruction(u, stg, prov):
    cands = constrained_parse(u)              # 多 parse：指代/量词/默认/言外之意
    out = []
    for c in cands:
        if not prov_gate.admit(c, prov):      # 权限单调性准入
            continue
        c.spatial = stg.ground(c.mentions)    # 视角索引接地；未接地 -> 标记
        c.phi     = to_stl(c.temporal_ops)    # before/after/until/while/every
        out.append(c)
    return InterpretationHull(out, prov)

# IP-265/266 STG + HULL：解释鲁棒安全集（在约束上取交集）
def robust_safe_set(hull, o_t):
    A = task_action_space(o_t)
    for c in hull.alive:                       # 每个合理解释都必须被满足
        A = {a for a in A if c.robustness(a) >= c.tau}
    return A                                   # 可能为空 => 不可调和

# IP-267 CHRONO：STL 监控 + 承诺台账（latching）
def monitor_and_ledger(ledger, xi_prefix, t):
    for c in ledger.active:
        rho = stl_robustness(c.phi, xi_prefix, t)
        if rho < 0:
            ledger.latch_violation(c, t)       # 违反不可被换解释清除
    ledger.advance_triggers(t)                 # dormant -> active
    return ledger

# IP-268 SCOPE：时间性 VoI（问/看/等），含截止期价格
def schedule(hull, o_t, budget, deadline):
    best = None
    for g in candidates(hull):                 # ask / look / wait
        if not budget.allow(g): continue
        if g.kind == "wait" and not guarded_wait_ok(hull, deadline): continue
        voi = expected_utility(hull, g) - utility(hull) \
              - LAMBDA_D * p_miss_deadline(g, deadline)
        score = voi - cost(g)
        if best is None or score > best.score: best = (g, score)
    return best if best and best.score > DELTA_VOI else None

# IP-269/270 BIG + TRC：行为性提问价值与截止期时空风险
def behavioral_ig(q, hull):
    return divergence(hull) - expected_divergence(hull, q)

def temporal_risk(hull, samples):
    return max(1 - p_sat(c, samples) for c in hull.active)

# IP-274 主闭环（继承 R69，仅在目标/约束层插入 LATCH）
def LATCH_RAS_round(M, obs, u=None):

        A_safe = M.hull.robust_safe_set(hull, o)
    if A_safe.empty:
        return M.safe_stop_and_escalate(hull)              # 意图层退避：不动

    ledger = M.chrono.monitor_and_ledger(M.ledger, M.last_action, M.t)
    lam  = M.efs.risk_scale(...)                           # R69/R68 动作层退避照旧
    k    = M.c_ras_wm.certified_prefix(a, ..., wm_preds)
    J    = M.cert.issue(M.j_fluid, hull, R_t, ledger)      # J_LATCH
    return k, a, ledger, J
```

## 3. 推导

**引理 19（交集盾的语义鲁棒安全性）** 设 c* ∈ ℋ 为真实解释且 a ∈ A_safe(ℋ)，则 ρ_{c*}(a) ≥ τ_{c*} ≥ 0，即不违反真实约束。因此安全性只依赖「真实解释在 ℋ 内」这一 **hull 完备性**假设，而不依赖语义猜测的正确性。反之，若 hull 漏掉真实解释，交集盾对它不提供任何保证——这把 R70 的主要风险精确地定位到「解释集完备性」，而不是「分类器准确率」。

**引理 20（行为散度作为后悔上界）** 定义最坏后悔 Reg(a; ℋ) = max_{c∈ℋ}[J_c(a*_c) − J_c(a)]。对 a∈A_safe(ℋ)，有 Reg(a; ℋ) ≤ D_ℋ（不同解释的最优值差被 D_ℋ 界住）。系：D_ℋ 同时是安全度量（交集是否为空）与效用度量（后悔上界）；因此按 BIG 提问可直接降低后悔上界，而按语义熵提问未必。

**引理 21（等待的期权价值与截止期约束）** 对 guarded wait 时长 Δ：OV(Δ) = E[U(ℋ_{t+Δ})] − U(ℋ_t) − λ_d·P(miss|Δ) − c_wait·Δ。若期间无任务动作且不变量保持，则等待不改变安全性，只改变信息与截止期。OV 对截止期压力单调不增：越接近 deadline，等待越不值。系：「等」不是免费的；它和探针一样受安全包络（这里是**时间包络**）约束。

**引理 22（权限单调性下的注入安全性）** 若准入控制满足定义 321 的单调性，则对任意注入指令序列，A_safe 单调不增：A_safe(ℋ ∪ ℰ_inject) ⊆ A_safe(ℋ)。因此注入只能造成**可用性风险**（可行动集合缩小甚至为空），不能造成安全风险。剩余风险是拒绝服务与过度约束，由预算、升级与超时停机兜底。

**定理 18（LATCH 严格包含 FLUID-RAS / R68）** 当 |ℋ|=1 且无时序承诺时，LATCH 的 A_safe 退化为单契约可行集，SCOPE 退化为 R69 MINT，CHRONO 退化为 R69 的 C-RAS-WM 前缀认证，故 LATCH ≡ FLUID-RAS；再当 VoI≤c 时 ≡ R68。对一般 ℋ，LATCH 的最坏情形（对所有解释取交集）不弱于「取最保守解释 + R69」，且澄清只能扩大 A_safe，故在匹配前者的安全性下获得效用增益。⇒ 安全侧对 R69 不做让步，语义侧把 R69 作为单解释边界。

**定理 19（语义纪律下的控制连续与无「解释洗白」）** 若解释切换仅在 replan 边界 B 且承诺 latching（定义 319/324），则：(a) 控制信号在切换点连续（切换后仍过 C-RAS-WM 且 A_safe 非空）；(b) 任何已发生的违反不能被后续重解释清除，因此系统不能通过「重新理解」来抹掉违规——这是 R68「缓变故障被标定吸收」在语义层的对偶禁令。系：证书不可被语义更新追溯性伪造。

## 6. 本轮最大风险

**一句话**：LATCH-RAS 的安全性证明只对「我们枚举到的解释」成立——**若真实意图不在 ℋ 内（多义没穷尽、指代锚错、言外之意漏编译），交集盾会以一张形式合法的证书「证明」一个错误任务的安全，形式化于是把「误解」洗成了「已验证」**；这与 R69「问错比不问更危险」同构，但更隐蔽：R69 是问错，R70 是**理解错还盖了章**（certificate laundering of misunderstanding）。

**次级风险与缓解**：
1. **Hull 不完备 / literal genie**（契约满足但意图违背）→ hull 完备性审计（J_LATCH 字段）+ E303/E312 人类评审 + 保守默认与最小承诺；

3. **STL/空间接地规格错误**（监控器本身错）→ 监控器单元测试 + 双实现交叉校验 + E305；
4. **视角/坐标帧混淆**（robot 左 vs speaker 左）→ 视角显式参数 + 切换时重认证 + E302；
5. **指令注入 / 时空欺骗**→ 权限单调性准入 + ℰ_lang 对抗集 + 时钟/来源认证 + 引理 22；
6. **过度约束导致 DoS**→ 预算 + 升级 + 超时安全停机；明确这是可用性风险而非安全风险；
7. **解释抖动**→ replan 边界 + 解释稳定性 + latching 台账 + E315。

## 4. 推导

**引理 19（交集盾的语义鲁棒安全性）** 若真实解释 `c*∈ℋ` 且 `a∈A_safe(ℋ)`，则 `ρ_{c*}(a)≥τ_{c*}≥0`，不违反真实约束。安全性只依赖 hull 完备性，不依赖语义猜测；hull 漏解则无保证——风险被精确归因到「解释集完备性」。

**引理 20（行为散度 = 后悔上界）** 对 `a∈A_safe(ℋ)`，最坏后悔 `Reg(a;ℋ)≤D_ℋ`。`D_ℋ` 同时是安全度量与效用度量；按 BIG 提问可直接压低后悔上界，按语义熵提问未必。

**引理 21（等待的期权价值）** `OV(Δ)=E[U(ℋ_{t+Δ})]−U(ℋ_t)−λ_d·P(miss|Δ)−c_wait·Δ`；guarded wait 不改变安全性，只改变信息与截止期；OV 对截止期压力单调不增。等待与探针一样受时间包络约束。

**引理 22（注入下的权限单调性）** 若准入满足定义 321，则 `A_safe(ℋ∪ℰ_inject) ⊆ A_safe(ℋ)`；注入只能造成可用性风险，不能造成安全风险；剩余风险由预算、升级与超时停机兜底。

**定理 18（LATCH 严格包含 FLUID-RAS / R68）** `|ℋ|=1` 且无时序承诺时，HULL→单契约可行集、SCOPE→MINT、CHRONO→C-RAS-WM，故 LATCH≡FLUID-RAS；再 `VoI≤c` 时 ≡R68。一般 `ℋ` 下，交集盾不弱于「取最保守解释+R69」，澄清只扩大 `A_safe`，故匹配安全性并获得效用增益。

**定理 19（语义纪律与无「解释洗白」）** 解释仅在 replan 边界切换且承诺 latching ⇒ 控制连续；已发生的违反不能随后续重解释清除 ⇒ 证书不可被语义更新追溯性伪造。这是 R68「缓变故障被标定吸收」在语义层的对偶禁令。

## 7. 本轮最大风险

**一句话**：LATCH-RAS 的安全性证明只对「我们枚举到的解释」成立——**若真实意图不在 ℋ 内（多义没穷尽、指代锚错、言外之意漏编译），交集盾会以一张形式合法的证书「证明」一个错误任务的安全，形式化于是把「误解」洗成了「已验证」**；这与 R69「问错比不问更危险」同构但更隐蔽：R69 是问错，R70 是**理解错还盖了章**（certificate laundering of misunderstanding）。

**次级风险与缓解**：hull 不完备/literal genie（完备性审计 + E303/E312 + 最小承诺）；L2C 编译幻觉（约束解码 + 接地与可满足性检查）；STL/空间规格错误（双实现交叉校验 + E305）；视角帧混淆（显式参考系 + 切换重认证 + E302）；指令注入/时空欺骗（权限单调性 + ℰ_lang + 来源与时钟认证 + 引理 22）；过度约束 DoS（预算 + 升级 + 超时停机，明确为可用性风险）；解释抖动（replan 边界 + 解释稳定性 + latching 台账 + E315）。
