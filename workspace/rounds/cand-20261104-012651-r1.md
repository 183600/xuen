# 第 16 轮（研究线累计；本轮灵感循环第 1 轮）· EMBODY-SIT-VLA：本体感知驱动的场景创新工具调用

> 检索/复核日期：**2026-11-04（UTC）**。赛事身份不变：宇树 UniBot 世界挑战赛，G1 + Dex1，32 项桌面任务，通才单模型赛道。本轮灵感词：「本体感知」、「场景驱动创新」、「工具调用」。不推倒第 10-15 轮：FACT-VLA、GEO-RESIDUAL、CHUNK-SERVO、WAVE-SERVO、VOI-MAP、ZEST-VLA。本轮在 ZEST 之上加 L5：Embodiment-Aware Scene-Informed Tool-calling。

## 0. 先给直觉：ZEST 知道不信，但不知道用什么代替

第 15 轮 ZEST-VLA 用动作-观测残差 + conformal/CUSUM 得到信任门 m_t ∈ {TRUST,FALLBACK}。门触发时，VOI-MAP 的动作集被硬约束，SERVO 被禁用，退回手工几何原语。

这个设计解决了「何时不信」，但留下两个未付费假设：
A1. fallback 原语在当前本体姿态下可达且安全。
A2. 固定语法 pick/place/insert 能覆盖零样本场景的 affordance 错配。

在真实桌面上，这两条经常一起失效：机器人被夹在桌面边缘、目标在可达边界、物体需要侧向抓取或工具辅助。此时固定原语要么不可达、要么执行后仍失败，系统陷入 HOLD-LOOK-VLA 死循环。

本轮的直觉是：把「不信任」转化为「可执行的降级工具调用」。本体感知给出机器人此刻能做什么；场景驱动创新从当前语义地图中生成针对 affordance 差距的工具候选；工具调用把候选映射为确定性原语并在 WAVE-SERVO 下执行。

一句话押注：
> **ZEST 决定信不信，EMBODY-SIT 决定信不住时用什么工具、在哪里用、是否可达：用本体中心的可达性/可操作性过滤场景 affordance 生成的工具候选，形成风险受控的动态工具调用层，让零样本降级从固定语法升级为场景感知的可行工具调度。**

## 1. 三个灵感词落地

| 词 | 落地 | 不做什么 |
|---|---|---|
| **本体感知** | 在线计算本体中心可达集 R_t、可操作性椭球、碰撞自由空间；所有工具候选必须通过 EmbodimentFeasible 过滤 | 不训练本体估计网络；不引入新的学习模型 |
| **场景驱动创新** | 从语义地图 G_t 提取 affordance 差距：目标不可达、抓取方向冲突、需辅助工具。差距驱动工具候选生成，而非固定语法表驱动 | 不做大模型生成；不做 test-time 重规划学习 |
| **工具调用** | 工具库 T 为确定性原语 + 元工具 {REPOSITION, REGRASP, LOOK, USE_TOOL}。调用决策是符号化选择 + 成本/收益排序，仍通过 WAVE-SERVO 执行 | 不调用外部 LLM；不更新权重；不引入第二个学习策略 |

## 2. 形式化定义

### 2.1 状态与表示
- 机器人状态 s_t = (q_t, \dot q_t, x_ee, g_t)
- 语义地图 M_t，场景图 G_t = (V,E)，v_i 有位姿 p_i、类 c_i、affordance a_i
- ZEST 输出：信任模式 m_t，软胜任力 c_t，CUSUM S_t
- 本体感知输出：可达集 R_t(s_t,M_t)，可操作性 w_t = σ_min(J(q_t))

### 2.2 工具
工具 t ∈ T 满足 Pre(t,s,G,E) → 执行。Pre 为确定性谓词：可达、碰撞自由、力限制、夹爪状态。成本 c(t)，预期进度增益 Δ(t)。

### 2.3 场景驱动候选生成
Affordance 差距函数：
gap(o,u,s) = 1 - match(a_o, need(u,s))
若 gap > τ，触发工具生成：
C_t = { t | Pre(t) ∧ EmbodimentFeasible(t,s_t) ∧ scene_match(t,G_t) }

### 2.4 工具调用决策
在 FALLBACK 模式下：
t* = argmax_{t∈C_t}  [ Feas(t) * U_scene(t) / c(t) ]
其中 U_scene(t) = b_max * f_geo(p+δ) * affordance_gain(t)
Feas(t) = Reachable(t) * Manipulability(t) * CollisionFree(t) ∈ [0,1]

若 C_t 空 → HOLD 或 LOOK。

在 TRUST 模式下，工具调用层旁路，VOI-MAP 直接调度 SERVO/LOOK/VLA。

## 3. 与第 15 轮关系

L5 EMBODY-SIT 位于 ZEST 之上、VOI-MAP 之下：
L5 工具调用与本体过滤 → L4 ZEST 信任门 → L3 VOI-MAP → L2 WAVE-SERVO → L1 VLA

保留：ZEST 的残差、conformal、CUSUM、复检；VOI-MAP 的预算调度；WAVE-SERVO 安全。
升级：fallback 从固定语法 → 场景驱动的动态工具候选 + 本体可行性过滤。
剪枝：不新增学习模型；工具库手工可验证；本体感知用正向运动学 + 简化几何。

## 4. 可证伪假设

H1 工具可行性过滤降低不可达 fallback 尝试 ≥50%
H2 在几何 OOD 上，EMBODY-SIT 比固定原语成功率 +≥5pp，ID 不回归 >2pp
H3 场景驱动候选生成在 affordance 错配任务上召回 ≥80%
H4 本体感知错误不会导致碰撞率上升

## 5. 本轮最大风险

**本体估计与场景 affordance 提取的误差会产生“看起来可行实则碰撞”的工具调用，导致在 FALLBACK 模式下引入新的安全违规**，这是从静态语法走向动态工具调用必须付出的本体感知账。

# 第 16 轮产物 · EMBODY-SIT-VLA 技术报告

> 检索/复核日期：2026-11-04。对象：UniBot 世界挑战赛。本文在第 15 轮 ZEST-VLA 之上增加 L5 Embodiment-Aware Scene-Informed Tool-calling，形成完整五层架构。

## 0. 结论与边界
一句话结论：ZEST 决定信不信 VLA，EMBODY-SIT 在不信时用本体感知过滤场景生成的工具候选进行动态降级，零样本失败从固定语法回退升级为场景感知的可行工具调度，不引入新学习模型。
边界：本体感知用解析几何近似；工具库手工；不解决 OOD-G。

## 1. 符号定义
s_t = (q_t, \dot q_t, x_ee, g_t)
M_t：语义地图
G_t = (V,E)：场景图
R_t(s) = {x | ∃q: FK(q)=x ∧ ||q-q_t||≤Δ ∧ CollisionFree(x,M_t)} 可达集
w_t = σ_min(J(q_t)) 可操作性
m_t ∈ {TRUST,FALLBACK} ZEST 模式
c_t ∈ [0,1] 软胜任力
T：工具库，t 有 Pre(t), Eff(t), cost c(t)
Feas(t|s) = I[R_t∋target(t)] * min(1,w_t/w0) * CollisionFree(t)

## 2. 算法步骤
1. ZEST 更新：计算残差 r_tmp,r_geo,r_goal,r_dyn → s_b → e_b → S_b → m_t
2. 本体感知更新：FK, Jacobian, 简化可达球体 + 碰撞检查 → R_t,w_t
3. 场景图更新：VOI-MAP 提供 M_t → G_t
4. 若 m_t=TRUST：旁路 L5，直接 VOI-MAP 调度
5. 若 m_t=FALLBACK：
   a. 计算 affordance 差距 gap(o,u,s)
   b. 生成候选 C_t = {t | Pre(t) ∧ Feas(t)>θ_f ∧ scene_match(t,G_t)}
   c. 评价值 V(t)=Feas(t)*b_max*f_geo(p+δ)*gain(t)/c(t)
   d. t* = argmax V(t)，若空则 LOOK/HOLD
   e. 通过 WAVE-SERVO 执行 t*
6. 块结束复检：如第 15 轮 CUSUM 复检

## 3. 复杂度分析
本体感知：O(N_obj) FK + O(K) 碰撞近似，<0.3 ms
场景图提取：O(N_obj)
候选生成：O(|T|·N_obj)
排序：O(|T| log |T|)
总计 per block <1.0 ms，内存 <15 MB

## 4. 正确性论证
命题1 安全子集：所有工具执行仍经 WAVE-SERVO 且必须满足 Pre ∧ Feas>θ_f。由 WAVE-SERVO 无源性，工具调用不破坏限幅与碰撞安全。
证明：Feas 包含 CollisionFree；Pre 包含力/速度限制；执行路径与 ZEST 相同。
命题2 不退化：若 m_t=TRUST，L5 旁路，行为退化为 ZEST+VOI-MAP。
命题3 可达性保证：若 Feas(t)=0 则 t 不在 C_t，工具调用不会尝试不可达动作。

## 5. 已知风险
- 本体估计近似导致假阳性可达
- Affordance 提取依赖语义地图精度
- 工具库覆盖不全导致仍需 HOLD
- 复检与工具切换引入额外延迟

## 6. 实验设计
G13'：本体过滤降低不可达尝试 ≥50%
G14'：几何 OOD 成功率 +≥5pp vs 固定原语
G15'：碰撞率不升，p99 <150 ms
H1-H4 如 IDEA 区

## 7. 一句话风险
本体感知误差会让系统在 FALLBACK 模式下自信调用不可达或碰撞工具，这是动态工具调用比固定语法更危险的本体账。
