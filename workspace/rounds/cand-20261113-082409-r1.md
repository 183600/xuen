# 第 3 轮迭代（灵感循环 v3：「事件相机」×「小样本学习」）—— 从「周期性看外观」到「变化驱动 + 少样本校准」的进度哨兵

> 本轮是当前灵感循环的第 1 轮；为与状态文件中的 v2 连续，本文记为 v3。承接 v2 的 UIP-01′~15。
>
> v2 已经用规则证据确认：人为干扰的核心形态不是「换一个物体」，而是**把已完成进度反向撤回**——T14「拧开后再拧回去」、T16「叠好后翻开」、T17「合上后再打开」、T19「拉上后再拉开」、T27「叠好第二个后拿走第二个」。这轮的两个灵感词不是再加两个并列模块，而是换两条更底层的原理：**事件相机**说「变化本身就是信息，而且变化有方向」；**小样本学习**说「用极少量样本就能定义一个目标、一个未见物体、或一个异常」。二者合起来，正好补上 v2 旗舰最大的软肋：DCR-R 的验证器是「单帧外观 + 固定 k」，它看不清「反向」，也付不起高频重观测的延迟。

---

## 0. 本轮事实边界与直接推论

本轮**不新增外部检索事实**，沿用 v2 于 2026-11-12 核实的事实（32 任务计分点、`human_*` 反向撤回、开环动作块、JPEG 传输、metadata 只握手一次、单模型合规）。在动笔前先把四个**由接口约束直接推出**的边界写清楚，避免把「事件相机」想当然地当成评测期外设：

| 推论 | 内容 | 对方案的硬约束 |
|---|---|---|
| A. 触发只能在块边界生效 | `get_action(obs)` 返回动作块，评测端**整块执行完**才再次调用 | 事件机制不能中断块内执行；它的价值是**降低每次块边界核验的成本**，从而允许更小的 k，而不是「微秒级中断」 |
| B. 评测接口没有事件通道 | 只给 4 路 RGB（JPEG q95），没有 DVS/事件流 | 真事件相机只能做**训练期教师 / 离线数据源**；部署期必须用 RGB 帧差得到的**伪事件** |
| C. metadata 只握手一次 | 控制空间、obs 选择、图像缩放、块长在启动时定死 | 「事件自适应块长」只能表现为**每次返回 ≤ 声明的 K_MAX**，不能运行期改 metadata |
| D. 单模型合规 | 不能外挂第二个大模型或多个独立策略 | few-shot 的 support 必须来自 episode 内部或主骨干特征；原型、阈值、校准表不算「第二个模型」 |

这四条决定了本轮的正确提法：**不是「给机器人装事件相机」，而是「把事件相机的表示与触发原理，蒸馏进一个只吃 RGB 的少样本进度监视器」**。

## 1. 上轮清单诊断：问题不在「怎么重做」，而在「怎么知道被撤回」

- **UIP-01′ / UIP-09′（旗舰与次旗舰）**：v2 的验证器 `V(o_t,l,g)` 主要问「当前子目标**是否达成**」。这是**单帧外观**问题；而人为撤回是**时序导数**问题。拉链被拉开的那一瞬间，拉链仍然「是拉链」，单帧分类器看到的仍是同一条拉链；只有比较「刚才合上的边缘正在反向移动」才能更快发现。固定 k 又把核验成本乘上了「每 k 步一次完整感知」。
- **UIP-12（DRF）**：v2 的扰动工厂只造「几何上的反向动作」，但没有把扰动组织成**变化模式**，也没有组织成 few-shot episode；数据造出来了，验证器却学不到「哪种变化是撤回」。
- **UIP-13（ACS）**：v2 按「任务阶段」选 k，是开环的时间表；它不知道**此刻是否真的发生了变化**，也不知道**人类是否刚刚完成了撤回**。
- **UIP-14（MSGR）**：技能图解决了「任务→技能」的路由，但没有解决「未见物体如何用少量样本落到技能节点上」。
- **结论**：v2 的「扰动恢复闭环」方向是对的，但**感知原理**（单帧外观）与**调度原理**（固定时间表）都该换。这正是两个灵感词的切入点。

## 2. 两个灵感词：先直觉，再严谨定义

### 2.1 事件相机（Event Camera / DVS）

**直觉解释。** 人看到「拉链被拉开」，不是因为重新识别了整条拉链，而是因为**刚刚合上的那条边在反向移动**。事件相机正是只报告这种「亮度发生变化的像素，以及变化的正负方向」，不报告静止的外观。它有三个对本题极重要的性质：① **变化即信息**，静止区域不产生数据，计算和带宽随「变化量」而不是「像素总量」增长；② **有极性**，能区分「往前」和「往回」；③ **高时间分辨率 / 高动态范围**，适合捕捉接触、滑动、插入到底、以及人手快速抽回这类瞬态。对 UniBot 来说，最值钱的不是「更高清的图」，而是**「刚刚发生了什么方向的变化」**。

**严谨定义。** 真实事件相机的输出是一个异步事件序列

`E = { e_k = (t_k, x_k, y_k, p_k) }`，其中 `p_k ∈ {+1, -1}`，

当像素 `(x,y)` 的对数亮度变化超过阈值 `C` 时触发：

`| log I(t_k,x,y) - log I(t_{k-1},x,y) | > C`，`p_k = sign( log I(t_k,x,y) - log I(t_{k-1},x,y) )`。

**部署期我们拿不到 `E`**，只能从相邻两帧 RGB 构造**伪事件**。设块边界观测为 `I_t`、`I_{t-k}`，定义有符号变化场

`D_t(x,y) = I_t(x,y) - I_{t-k}(x,y)`，

在任务相关区域 `R_i`（由 few-shot 原型/分割给出）上的**事件能量**为

`E_t(R_i) = Σ_{(x,y)∈R_i} |D_t(x,y)|`。

更进一步，我们不需要「亮度变化」，而需要「**进度变化的方向**」。设 `φ(o)` 是共享骨干给出的观测嵌入，`u` 是任务进度方向（由语言 + 少样本目标原型定义），定义**有符号进度坐标**

`z_t = <φ(o_t) - φ(o_0), u> / ||u||²`，

以及**单调包络** `M_t = max_{s≤t} z_s`。则「被撤回」的程度是

`R_t = M_t - z_t`。

**回归检测**用单边 CUSUM：`S_t = max(0, S_{t-1} + ΔR_t - ν)`，当 `S_t > h` 时报警（`ν` 是漂移容忍，`h` 是报警阈值）。这比「单帧是否达成」多用了**时间方向**，也比「固定阈值掉点」更抗噪声。

### 2.2 小样本学习（Few-Shot Learning）

**直觉解释。** 小样本学习不是「用很少数据把一个大模型从零训出来」，而是**用少量样本定义一个概念**：给 3 张未见物体的图，模型就能在嵌入空间里形成它的「原型」；给 1–3 段人为撤回的片段，模型就能校准「什么算异常」。UniBot 的测试分布恰好是「32 个已知任务 + 未见物体/背景 + 零公开数据的 human_* 干扰」：已知任务可以预训练，**新概念只能靠少样本在 episode 内定义**。此外，每个 episode 开头的几帧，本来就是天然的 support set。

**严谨定义。** 设任务分布 `p(T)`，一个 `N-way K-shot` episode 含 support `S = {(x_i,y_i)}_{i=1..N×K}` 与 query `Q`。用嵌入 `f_θ` 计算类原型

`c_n = (1/K) Σ_{i: y_i=n} f_θ(x_i) / ||·||`，

原型损失为

`L(S,Q;θ) = - E_{(x,y)∈Q} log [ exp(-d(f_θ(x), c_y)) / Σ_n exp(-d(f_θ(x), c_n)) ]`。

元训练目标是 `θ* = argmin_θ E_{T~p(T)} [ L(S_T,Q_T;θ) ]`。在「单模型」约束下，`θ` 是一条共享骨干，任务/技能差异用**参数高效适配器** `ψ_T` 表示，`ψ_T` 可由少量梯度步或闭式原型得到。

对**开放集的「被撤回」异常**，我们不用分类器，而用**非一致性分数 +  conformal 校准**：在若干「正常、无撤回」的校准 episode 上计算分数 `s_t`，取 `λ = Quantile_{1-α}({s_t})`；当 `s_t > λ` 时报警。在可交换性假设下，`P(误报) ≤ α`；人类干扰的时序非平稳会破坏可交换性，因此实际要用**分块 conformal / 在线 conformal**，把 `α` 当作近似预算而不是硬保证。

### 2.3 合起来：EFPS（Event-triggered Few-shot Progress Sentinel）

**直觉解释。** 先用极便宜的「变化门」判断「有没有值得看的变化」；只有门被触发时，才用「少样本原型 + 时序逻辑」判断「这个变化是不是把已完成步骤撤回了」；如果是，就在预算内重做该子目标。这样，**事件相机负责「什么时候看」，小样本学习负责「看什么、算不算异常」**。

**严谨定义（本轮旗舰的形式化）。** 把每个任务的计分步编译成有序时序逻辑公式

`φ = ◇(p_1 ∧ ◇(p_2 ∧ ... ∧ ◇p_S))`，

其中原子命题 `p_i(o_t) = 1[ d(φ(o_t), c_i) ≤ λ_i ]`，`c_i` 是第 `i` 步目标状态的少样本原型，`λ_i` 是 conformal 阈值。监视器维护当前步索引 `g` 与每步状态

`status_i ∈ {pending, ongoing, done, regressed}`，

其中 `regressed` 定义为「存在 `t'<t` 使 `p_i(o_{t'})=1`，且当前 `p_i(o_t)=0` 并持续 `m` 个块边界」。事件门控只在

`E_t(R_i) > θ` 或 `h_i(t) > η`（`h_i` 为人为干扰的风险函数，见 UIP-19）

时才对 `p_i` 做昂贵求值；否则沿用上次状态（带**有界 stale 假设**）。报警后进入 `redo`，重做步 `i`，并由 UIP-15 的延迟/抖动/次数预算约束。

## 3. 本轮瓶颈假设（更新）

- **H1（最高杠杆）**：人为撤回可由「有符号进度增量」检测；时序差分比单帧外观更早、更稳，尤其在 T14/T16/T17/T19/T27 这类「完成后才被反向」的任务上。
- **H2（事件相机的正确用法）**：真事件/高帧率仿真事件只做**训练期教师**；通过自监督「动作方向/接触起点」任务学到的变化编码器，可以蒸馏到 RGB 伪事件编码器，部署期不需要事件硬件。
- **H3（小样本的正确用法）**：未见物体与目标状态靠 episode 内 `K=1–5` 的原型即可显著好于纯语言零样本；但不要期待它「解决」未见物体，只期待它「把未见物体锚定到已有技能」。
- **H4（校准）**：用少量真实/合成撤回片段做 conformal 校准，可以把「误报→反复重做」的代价压到可控范围；校准集太小时保证很脆（见产物区玩具实验）。
- **H5（时序先验）**：`info.json` 的 `human_*` 文本往往写明「在哪一步之后」干扰，因此「干扰风险函数」比「均匀随机检查」更省、更及时；这能补上伪事件在快速/遮挡撤回上的盲区。
- **H6（实时性）**：事件门控把每次核验从「完整感知/大模型」降到「帧差 + 轻量编码」，省下的预算应换成**更小的 k**；否则事件原理的收益会被块长吃掉。

## 1. 旗舰深潜：UIP-01″ · EFPS（Event-triggered Few-shot Progress Sentinel）

### 1.1 它到底解决什么

v2 的 DCR-R 在每次块边界问三个问题中的第一个：

1. **「当前子目标完成了吗？」**（单帧外观，v2 的主力）
2. **「刚刚有没有发生一个反向变化？」**（时序导数，v2 的缺口）
3. **「这个变化是否值得我现在重做？」**（代价/收益，v2 只靠固定阈值）

EFPS 把 2、3 补上，并把 1 从「每 k 步都做」改成「有变化/高风险时才做」。它不是替代 v2 的计分步安全网，而是给安全网装上**方向传感器**与**事件触发器**。

### 1.2 形式化

设 episode 的观测序列为 `o_t = (I_t^1..I_t^4, q_t, l)`，其中 `I_t^j` 是 4 路相机，`q_t` 是本体状态，`l` 是语言。共享骨干给出嵌入 `φ(o_t)`。

**（a）有符号进度坐标。** 对任务 `T` 的第 `i` 个计分步，用 few-shot 原型定义进度方向 `u_i`（从初始状态原型指向目标状态原型；若目标不可见，则由语言条件化的方向头给出）。令

`z_{i,t} = <φ(o_t) - φ(o_0), u_i> / ||u_i||²`，

`M_{i,t} = max_{s≤t} z_{i,s}`，`R_{i,t} = M_{i,t} - z_{i,t}`。

`R_{i,t}` 是「曾经到过的最好进度」与「当前进度」的差；它天然对「完成后被撤回」敏感，而对「正常前进中的小幅抖动」不敏感。

**（b）事件门控。** 在块边界比较 `I_t` 与 `I_{t-k}`：

`D_t = I_t - I_{t-k}`，`E_{i,t} = Σ_{(x,y)∈R_i} |D_t(x,y)|`。

其中 `R_i` 是第 `i` 步的任务相关区域（由 few-shot 原型/轻量分割给出）。只有当

`E_{i,t} > θ_i` 或 `h_i(t) > η`

时，才对该步运行昂贵验证（UIP-17/18）；否则沿用上次状态，并假设「无变化则无状态变化」（有界 stale 假设）。

**（c）回归统计量。** 对已完成的步维护单边 CUSUM：

`S_{i,t} = max(0, S_{i,t-1} + ΔR_{i,t} - ν_i)`，

当 `S_{i,t} > h_i^cusum` 且持续 `m` 个边界时，置 `status_i = regressed`。这里 `ν_i` 吸收正常噪声/小幅回弹，`h_i^cusum` 控制灵敏度。

**（d）少样本谓词。** 对第 `i` 步目标，用 `K` 个 support 观测（来自公开数据同任务演示，或 episode 前 `L` 帧的自监督目标）计算原型

`c_i = (1/K) Σ_k f_θ(o_i^k) / ||·||`，

谓词 `p_i(o_t) = 1[ d(f_θ(o_t), c_i) ≤ λ_i ]`。`λ_i` 由 conformal 校准得到（UIP-18），而不是手调。

**（e）有序时序逻辑与状态机。** 任务公式

`φ = ◇(p_1 ∧ ◇(p_2 ∧ ... ∧ ◇p_S))`，

监视器维护 `g`（当前步）与 `status_i`；`regressed` 的语义是「`p_i` 曾在某个 `t'` 为真，当前为假」。报警后 `g ← i`，在 UIP-15 的预算内重做，而不是从头重来。

### 1.3 与 v2 的差异

| 维度 | v2（UIP-01′/09′） | v3（UIP-01″） |
|---|---|---|
| 感知量 | 单帧外观 / 几何谓词 | 有符号时序变化 + 少样本原型 |
| 触发 | 固定每 k 步 | 事件能量 + 干扰风险函数 |
| 阈值 | 手工/经验 | conformal 校准（带误报预算） |
| 未见物体 | 语言条件化 | K-shot 原型 + 语言，episode 内适应 |
| 撤回检测 | done/fail/ongoing | 显式 `regressed`，方向敏感 |
| 代价 | 每 k 步完整核验 | 安静时几乎零昂贵核验；省下的预算换小 k |

### 1.4 为什么两个词缺一不可

- 只有事件相机：知道「有变化、往哪变」，但不知道「这个变化是不是任务相关的撤回」，也不知道「多确信才该重做」。
- 只有小样本：能用少量样本定义目标和异常，但每个块边界都跑一遍原型匹配，代价高、延迟大。
- 合起来：**事件门控把昂贵的小样本判断限制在少数关键时刻**；小样本判断把事件从「任意变化」提升为「有语义的撤回」。这正是 v3 的核心。

## 2. 事件相机：UIP-16 EV-SIM + 伪事件哨兵

### 2.1 真实事件与伪事件

真实事件流：`e_k=(t_k,x_k,y_k,p_k)`，`p_k=sign(Δlog I)`，由亮度变化阈值触发。它提供微秒级时间分辨率、高动态范围、低冗余，但**评测接口没有这个通道**。

部署期伪事件：`D_t=I_t-I_{t-k}`，在 ROI 上取 `E_{i,t}=Σ|D_t|`，并用 `sign(<D_t,u_i>)` 近似「变化极性」。这比完整光流便宜得多，也足够做「有没有反向变化」的门控；真正的方向判断交给少样本原型/轻量头。

### 2.2 EV-SIM 数据流水线（离线，权限内）

1. **公开数据侧**：解码 32 个数据集的 4 路 480×640 AV1；对相邻帧做可选插值（提高到 120–240Hz），再用事件模拟器（如 v2e/ESIM 类方法）生成事件体素网格。标签不用人工：用动作/状态差分给出「运动方向」监督。
2. **Gazebo 侧**：用 UIP-11 的场景，以高物理频率 + 高渲染帧率生成「反向撤回」片段；直接得到高时间分辨率事件与对应的计分步真值。
3. **真机侧（可选、少量）**：在自有台架上装事件相机，只采 5 个接触密集任务（T26 插网线、T10 插插头、T12 开锁、T14 倒药、T16 叠毛巾），作为「真实事件纹理」的校准锚点。
4. **自监督变化编码器**：训练 `f_event` 从事件体素预测「动作方向 / 接触起点 / 进度增量符号」。这些标签来自动作与状态，不需要额外标注。
5. **蒸馏回 RGB**：用一致性损失让 `f_rgb(D_t)` 逼近 `f_event(E_t)`；部署只跑 `f_rgb`，事件相机不出现在评测路径上。

### 2.3 它买到了什么、没买到什么

**买到：**
- 低成本的「变化门」，把昂贵核验从每 k 步一次降到「有事件时」；
- 方向/极性，直接对应「反向撤回」；
- 接触/滑动/插入到底的瞬态特征（事件相机的高时间分辨率在训练期可教给 RGB 编码器）；
- 高动态范围带来的光照鲁棒性（训练期数据增强）。

**没买到：**
- 评测期没有事件流；伪事件仍受 RGB 帧率与块长限制；
- 30Hz 帧差无法恢复 30Hz 以上的快速撤回；事件原理不能突破观测率；
- 伪事件对相机自运动敏感，需要用本体/光流做补偿，否则机械臂运动会被误判为「变化」。

### 2.4 成本模型

设一次昂贵核验（少样本原型匹配 + 时序逻辑）成本为 `C_v`，一次伪事件门控成本为 `C_e ≪ C_v`。v2 每 `k` 步付 `C_v`；v3 在安静期只付 `C_e`，在事件期付 `C_e + C_v`。若事件稀疏度为 `ρ`，则平均成本约 `C_e + ρ·C_v`。省下的预算用于**减小 k**，从而降低对撤回的反应延迟——但延迟下界仍是 `k·Δt_frame`，这就是本轮最大风险的来源。

## 3. 小样本学习：UIP-17 FSL-PM / UIP-18 CBRD / UIP-19 DHP

### 3.1 UIP-17 · FSL-PM（Few-Shot Prototype Memory）

- **物体原型**：从语言指令 + episode 前几帧（或公开数据同任务 support）构建 `c_obj`，用于未见物体的定位/分割 ROI。
- **目标状态原型**：每个计分步的「完成态」用 `K` 个 support 帧表示；`p_i` 是当前嵌入到 `c_i` 的距离谓词。
- **技能原型**：把 32 任务压缩成 ~10 个技能节点（抓/放/插/倒/拉链/折叠/堆叠/分拣/开合/挑取），每个节点有原型；`UIP-14′` 用软路由 + 通用回退。
- **单模型合规**：原型是**非参数记忆**，不是第二个模型；所有嵌入来自同一条共享骨干。适配器 `ψ_T` 与骨干一起训练/冻结，不引入外部大模型。

### 3.2 UIP-18 · CBRD（Conformal Calibrated Regression Detector）

- **分数**：`s_t = R_t` 或 `s_t = -Δz_t`（越像撤回分数越大）。
- **校准**：在若干「正常、无撤回」的 episode 上收集 `{s_t}`，取 `λ = Quantile_{1-α}`。
- **报警**：`s_t > λ` 且持续 `m` 个边界。
- **保证与 caveat**：可交换性下 `P(误报)≤α`；人类干扰的时序非平稳、episode 内相关，因此实际用**分块 conformal**（按 episode/时间段分块）或**在线 conformal / e-value**，把 `α` 当预算而非硬保证。
- **少样本的意义**：不是「用 5 个样本训练一个分类器」，而是「用 5–50 个校准 episode 把阈值放到可控误报率」；校准集大小对实际误报的影响见 §6.3。

### 3.3 UIP-19 · DHP（Disturbance Hazard Prior）

`info.json` 的 `human_*` 往往写明干扰发生的**时机**（「拉上后再拉开」「叠好第二个后拿走第二个」）。把它编码成第 `i` 步完成后的风险函数：

- 基函数：指数/Weibull `h_i(τ)=λ_i` 或 `h_i(τ)=k_i/η_i (τ/η_i)^{k_i-1}`，`τ=t-t_i^done`；
- 先验：`λ_i ~ Gamma(a_0,b_0)`（弱信息）；
- few-shot 更新：观测到 `n_i` 次干扰后，`λ_i | data ~ Gamma(a_0+n_i, b_0+ΣΔτ)`；
- 触发：当 `P(τ < Δt | data) > η` 时，在「守窗口」内强制小 k 并核验，即使伪事件能量不高。

DHP 是对伪事件盲区的**兜底**：如果撤回太快/被遮挡，事件门可能漏；但「刚完成第 i 步后的高风险窗口」仍然会强制你看一眼。

## 4. v2 各项的升级落点

- **UIP-02′ SSG**：把 `scoring_points` 直接编译成 §1.2(e) 的有序公式与权重；末步分值更大 ⇒ 末步的 `λ_i`/`m` 更保守，前置步更激进。
- **UIP-11 GSO**：保留几何谓词判分；新增「高帧率渲染 + 事件模拟」输出，供 UIP-16 使用；仍只做**结构/顺序裁判**，不做像素级成败裁判。
- **UIP-12′ DRF-E**：在 Gazebo 里按 `human_*` 文本脚本化「拧回/翻开/拉开/拿走/挪底座」，以高帧率渲染并模拟事件；输出 `(干扰前 → 撤回 → 恢复)` 三元组 + 事件/伪事件对，打包成 few-shot episode。
- **UIP-13′ ACS-E**：安静时返回 `K_MAX` 步；事件/高风险时返回 1–2 步并重规划。metadata 只声明 `K_MAX`，运行期返回 `≤K_MAX`。
- **UIP-14′ MSGR-FS**：技能图节点 + 少样本原型路由；软路由避免跨任务污染，通用回退头兜底。
- **UIP-15 CSG**：给 `regressed` 重做设延迟预算、抖动上限、最大重做次数；动作形态平滑，避免可信度异常。
- **UIP-08′ LAT-ENG**：共享骨干、批处理、每端口 KV/历史隔离；只声明必要 obs 键、少堆叠帧、按需降分辨率，减少 JPEG 数量。

## 5. 关键算法伪代码

```python
import numpy as np

class EFPS:
    """UIP-01″: event-gated, few-shot, conformal progress sentinel."""
    def __init__(self, backbone, policy, memory, monitor, governor,
                 K_MAX=8, theta=0.02, eta=0.2):
        self.backbone, self.policy = backbone, policy
        self.memory, self.monitor = memory, monitor
        self.governor = governor
        self.K_MAX, self.theta, self.eta = K_MAX, theta, eta

    def reset(self):
        self.policy.reset()
        self.g = 0
        self.redo = 0
        self.prev = None
        self.memory.reset_episode()
        self.monitor.reset()

    def get_action(self, obs):
        if self.prev is None:                      # first call: build support
            self.memory.build_support(obs, n_shot=5)
            self.prev = obs
            return self.policy.get_action(obs, self.K_MAX)[:self.K_MAX]

        d = self._diff(obs, self.prev)             # UIP-16 pseudo-events
        k = self.K_MAX
        fired = self.monitor.triggered(d, self.g, self.theta, self.eta)

        if fired:                                  # only now pay for verification
            state = self.monitor.verify(obs, self.g)   # UIP-17 + UIP-18
            if state == "regressed" and self.governor.allow_redo():
                self.monitor.mark_regressed(self.g)
                self.g = max(0, self.g - 1)
                self.redo += 1
                k = 1                              # UIP-13′: fast re-observe
            elif state == "done":
                self.monitor.advance(self.g)
                self.g += 1
                k = self.monitor.guard_k(self.g)   # UIP-19 high-hazard window
            else:
                k = 1                              # uncertain: keep watching
        else:
            k = self.K_MAX                         # quiet: long chunk

        self.prev = obs
        chunk = self.policy.get_action(obs, k)
        return chunk[:k]                           # always <= declared K_MAX
```

```python
# UIP-16/18/19: cheap signed change + CUSUM + conformal + hazard
def pseudo_event_and_regression(obs, prev, rois, u, cusum, nu, h):
    D = obs.images - prev.images
    energy = {i: np.abs(D[roi]).sum() for i, roi in rois.items()}
    dz = {i: float(np.dot(D[roi], u[i])) for i, roi in rois.items()}
    alarms = {}
    for i in energy:
        if energy[i] > theta_i:                    # event gate
            cusum[i] = max(0.0, cusum[i] - dz[i] - nu[i])
            alarms[i] = cusum[i] > h[i]
    return energy, alarms

def conformal_threshold(normal_scores, alpha=0.05):
    # block-conformal for temporally correlated episodes
    return np.quantile(normal_scores, 1.0 - alpha, method="higher")

def hazard_trigger(t, t_done, posterior_gamma, eta=0.2):
    a, b = posterior_gamma                       # Gamma(a,b) posterior for lambda
    lam = a / b
    return (1.0 - np.exp(-lam * (t - t_done))) > eta
```

```python
# UIP-19: few-shot Bayesian update of the disturbance hazard
def update_hazard(prior_gamma, observed_dt):
    a0, b0 = prior_gamma
    n = len(observed_dt)
    return (a0 + n, b0 + float(np.sum(observed_dt)))
```

## 6. 本轮玩具实验（合成，非真机）

> 目的不是证明 EFPS 在真机上有效，而是隔离一个设计问题：**当人为撤回只发生在动作块之间，事件门控能否在保持检出质量的同时，把昂贵核验降下来？** 以及**少样本校准集要多大才可信？**
>
> 代码与结果：`exp/efps_toy_sim.py`、`exp/efps_toy_results.json`。1000 个 episode，3 个计分步（权重 0.3/0.3/0.4），30Hz，块长 `k∈{4,8,16}`，每个已完成步骤以 0.5 概率被人为反向撤回（反向速率 1/s，目标进度 0–0.6），观测噪声 `σ=0.005`。所有方法在同一批 episode 种子上配对比较。

### 6.1 对照

- **B0**：v2 的「只看当前子目标」几何验证（不看已完成步）。
- **B1**：周期性全量重查所有已完成步（相当于「用最贵的方式获得时序信息」）。
- **V3**：事件门控 + 有符号 CUSUM（本轮的哨兵），只在事件能量超过阈值时做全量核验。

### 6.2 结果

| k | 方法 | 成功率 | 加权步骤分 | 撤回检出率 | 检出延迟(s) | 误报/局 | 昂贵核验/局 |
|---|---|---|---|---|---|---|---|
| 4 | B0（v2） | 0.134 | 0.514 | 0.000 | — | 0.000 | 151.0 |
| 4 | B1（周期全查） | 0.439 | 0.681 | 0.938 | 0.199 | 0.000 | 453.0 |
| 4 | **V3（事件门控）** | **0.439** | **0.681** | **0.938** | **0.200** | **0.000** | **11.9** |
| 8 | B0（v2） | 0.107 | 0.487 | 0.000 | — | 0.000 | 76.0 |
| 8 | B1（周期全查） | 0.532 | 0.741 | 0.938 | 0.265 | 0.000 | 228.0 |
| 8 | **V3（事件门控）** | **0.532** | **0.741** | **0.938** | **0.265** | **0.000** | **6.8** |
| 16 | B0（v2） | 0.140 | 0.508 | 0.000 | — | 0.000 | 38.0 |
| 16 | B1（周期全查） | 0.531 | 0.735 | 0.937 | 0.413 | 0.000 | 114.0 |
| 16 | **V3（事件门控）** | **0.533** | **0.737** | **0.931** | **0.413** | **0.003** | **4.8** |

**读表：**

1. **v2 的盲区是真实的**：B0 在反向撤回下丢失约 0.17–0.25 的加权步骤分；它根本不会对已完成步报警。
2. **事件门控不损失检出质量**：V3 与 B1 在成功率、步骤分、检出率、延迟上几乎一致；但昂贵核验少了 **24–38 倍**（k=4：453→11.9；k=8：228→6.8；k=16：114→4.8）。
3. **省下的预算必须换成更小的 k**：检出延迟随 k 近似线性（k=4/8/16 → 0.20/0.27/0.41s）。这直接验证了本轮最大风险：**事件原理不能突破块长下界**。
4. **误报在合成噪声下接近 0**，但这不代表真机；真机的光照、遮挡、自运动会让伪事件更脏，必须靠 UIP-18 的 conformal 与 UIP-19 的风险窗口兜底。

### 6.3 少样本校准的玩具结果

**原型准确率**（12 类合成嵌入，每类 `K` 个 support，query 为新样本）：

| K | 1 | 3 | 5 | 10 |
|---|---|---|---|---|
| 准确率 | 0.381 | 0.581 | 0.659 | 0.742 |

**Conformal 误报率**（`α=0.05`，正态分数，400 次重复；报告经验 FPR 的均值与 5–95% 区间）：

| 校准集大小 | 10 | 20 | 50 | 100 | 200 |
|---|---|---|---|---|---|
| 平均 FPR | 0.118 | 0.087 | 0.067 | 0.061 | 0.055 |
| 5–95% 区间 | 0.015–0.304 | 0.020–0.195 | 0.018–0.138 | 0.028–0.101 | 0.032–0.083 |

**读表：**

- `K=3–5` 的原型已经把未见类别从「接近随机（1/12≈0.083）」拉到 0.58–0.66，说明少样本适合做**锚定/适应**，不适合期待「从零解决未见物体」。
- 校准集只有 10 个 episode 时，名义 `α=5%` 的 95 分位误报率可达 30%；要到 ~100–200 个校准 episode 才接近名义值。**few-shot 不是免费午餐**：要么多采少量真实干扰片段，要么用分块/在线 conformal，并在部署时保守设 `α`。

### 6.4 实验局限

- 合成实验把「进度」简化为一维标量，把「伪事件」理想化为进度差分；没有真实图像、遮挡、自运动、接触动力学。
- 没有模拟「重做失败」和「人类二次干扰」；UIP-15 的预算护栏未进入仿真。
- 因此这些数字只能支持**机制层面的 sanity check**，不能当作真机或 GSO 的绩效承诺。

| E210 | 接触密集任务子集（T10/T12/T14/T16/T19/T26） | 步骤分 / 重做次数 | 事件/接触特征收益最大处应可测 |

> 所有真机结论提测前一律标注为 **GSO/合成代理**，不得当真机结论；真机只做锚点校准（E208）。

## 8. 合规与风险（本轮新增重点）

- **单模型合规**：EFPS 的所有组件共享一条骨干；few-shot 原型是**非参数记忆**，conformal 是阈值，事件编码器蒸馏进同一骨干。不得在推理期调用外部 VLM 做验证器。
- **事件相机不在评测路径**：EV-SIM 只做离线训练/蒸馏；部署只吃 RGB 伪事件。任何「评测期有事件流」的假设都是错误的。
- **伪事件的三个污染源**：相机自运动、光照突变、遮挡。必须用本体/光流补偿 + 事件能量归一化 + conformal 保守阈值；否则误报会触发无谓重做。
- **conformal 的可交换性陷阱**：人类干扰在 episode 内相关、跨 episode 非平稳；用分块 conformal / 在线 conformal / e-value，并把 `α` 当预算。校准集太小（<~50）时不要相信名义覆盖率（§6.3）。
- **少样本的期望管理**：`K=1–5` 是「锚定未见物体/目标」，不是「从零学会新任务」；技能路由错误要有软路由与通用回退。
- **仿真过拟合**：GSO/DRF-E 仍是仿真；事件模拟不等于真实事件；必须保留真机锚点（E208）。
- **延迟红线**：事件门控省的是**核验算力**，不是**观测延迟**；延迟下界由 k 和帧率决定。不能对外宣称「微秒级反应」。
- **接口红线**：返回块长 ≤ 声明 `K_MAX`；形状/dtype/token 严格按 README；动作统计要平滑（UIP-15）。

## 9. 资源与时间线（粗排）

- **第 1–2 周**：在 3–5 个代表任务上跑通 EV-SIM（公开视频 → 伪事件 → 事件编码器；Gazebo 高帧率 → 事件）；建立「动作方向/接触起点」自监督标签。
- **第 3–4 周**：FSL-PM 原型 + CBRD conformal；在公开数据上做 K-shot 离线评估；确定每任务的 ROI 与 `K`。
- **第 5–6 周**：EFPS 状态机 + ACS-E 接入；用 GSO 的脚本化反向撤回做闭环；跑 E201/E205/E207。
- **第 7–8 周**：DRF-E 扩充扰动-恢复数据；DHP 风险先验；跑 E202/E203/E204/E206/E209。
- **第 9 周起**：预约真机，做 E208 锚点校准；把 GSO 的结论逐项对齐真实步骤分。
- **持续**：维护「合成 → GSO → 真机」三级证据链，任何一级的结论不得越级外推。

## 10. 本轮最大风险 & 押注

**最大风险**：若把事件相机的「变化即信息」当成评测期事实，而忽略它只能以块边界伪事件的形式出现，整个方案会在最快的人为撤回上系统性滞后；因此本轮的赌注是**「用事件门控省下的算力换更小的 k」**，而不是「事件本身更快」。
