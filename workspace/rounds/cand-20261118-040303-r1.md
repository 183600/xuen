# 第 1 轮（UniBot 线 · 本轮灵感：「移动操作」×「姿态估计」）

> **基线说明**：本文件此前承载 UniBot-SAGE（抓取 × 技能学习 × 地形适应）以及更早的 MetricVoiceGauge 线。本轮把问题**重新基线化**到「移动操作 × 姿态估计」子线，但不推翻既有事实：官方 32 个桌面任务、G1 + Dex1、4 路相机、单人通才模型赛道、`metadata / get_action / reset` 接口、`control_space ∈ {joint, ee}`、`obs_delta_indices` / `action_chunk_size` / `image_resize`、N 个连续端口、延迟与动作规律性审计等约束继续沿用。SAGE 的抓握确认、技能路由、chunk 缝合与审计层作为邻线封存，本轮只在必要处引用其结论。
>
> **数据纪律**：本轮新增数字全部来自本地官方数据缓存 `exp/duo_rows_cache/`（15/32 任务、91 episodes、42,800 帧、30 Hz；含 state/action，不含图像）与 teaser 榜快照 `exp/r16_leaderboard_stats.json`。脚本与结果已落盘：`exp/mob_pose_analysis.py`、`exp/pose_calib_analysis.py`、`exp/pivot_summary.py`、`exp/mob_pose_results.json`、`exp/pose_calib_results.json`、`exp/pivot_summary.json`，可复算。榜单仍是**占位/teaser**，只作结构参考，不当作官方终稿。

## 0. 一句话直觉

**在这个赛道里，「移动操作」不是让 G1 走路，而是让它在「底座被钉死、姿态却没有被明说」的条件下做桌面操作；于是两个真正的杠杆是：把底座锚定（不要乱动），把姿态校准并相对化（不要相信绝对坐标）。**

## 1. 两个灵感的第一性原理

### 1.1 「移动操作」→ 先证伪「移动」，再定义「虚拟移动」

**直觉（先给解释）**：看到人形机器人 + 32 个桌面任务，第一反应自然是「移动 + 操作」。但一个严谨的研究者应该先检验零假设：**这 32 个任务里，移动/身体自由度到底贡献了多少行为？** 如果答案接近零，那么把它当成移动操作问题去设计，就是在给一个不存在的主变量分配模型容量、延迟预算和安全风险。数据给出的答案非常干脆：几乎为零。

**严谨形式（再给定义）**：设动作分解为 `a = (a_arm, a_grip, a_pivot, a_lower, a_base)`。若

`Var(a_pivot) + Var(a_lower) + Var(a_base) ≤ ε · Var(a)`

且身体状态在 episode 内准静态，则把身体自由度冻结在首帧值 `ξ_0`，策略行为的偏离被 `‖∂p_ee/∂ξ‖ · δξ` 界定。本轮在 15 个任务、42,800 帧上实测：

- `action.pivot` 的 episode 内平均标准差 **1.25e-4**；跨 episode 平均标准差 **2.82e-4**；
- `action.lower_body` 的 episode 内平均标准差 **3.62e-3**；
- `observation.state.waist_state_joint` 的 episode 内平均标准差 **5.57e-3 rad**（最大 0.0102 rad）；
- 原始动作方差分解：**手臂+夹爪 99.91% / pivot 0.002% / lower_body 0.088%**；
- `action.base_command` 的 x、y 分量恒为 0，仅保留一个常数 yaw≈0.74。

因此，**这不是「移动操作」，而是「固定底座的人形桌面操作」**。取末端杠杆 `r≈0.357 m`，冻结身体的上界位移约 `r · δξ ≈ 0.357 × 0.010 ≈ 3.6 mm`（把 lower_body 也算上约 6 mm），小于本轮测到的动作-观测位姿差（均值 16.5 mm），更远小于抓取/插入的失败尺度。**冻结身体是近无损的。**

但「移动」并没有完全消失：它变成了**试时的底座放置分布偏移**。训练数据里每个任务的底座位置固定（跨 episode 的 pivot 标准差仅 2.8e-4），而评测在 N 台真机上运行，机器人相对桌面的放置不可能完全一致；5 类泛化场景中的「位置」也包含这类全局偏移。于是「移动操作」的正解是两层：

1. **不要把移动当自由度去学**（BaseLock：冻结 base / lower_body，只在明确需要时用有界腰部）；
2. **把底座放置当隐变量去估、去归一化**（SceneFrame：episode 开始时估计场景坐标系，动作在场景相对坐标里表达）。

在这个意义上我们仍然做「移动操作」，只是移动发生在**坐标系**里，而不是轮子里。

### 1.2 「姿态估计」→ 姿态不是观测，而是需要被标定的关系

**直觉（先给解释）**：大家默认 `observation.state.*_ee_pose_*` 就是位姿真值，直接把绝对位姿喂给策略。但本轮发现两个被忽略的事实：第一，同一帧的 `action` 位姿与 `observation` 位姿存在**系统性差异**；第二，这个差异**不是常数偏移**，它随末端速度变化。若把它当噪声，插入类任务会被一个厘米级的固定偏差直接压死；若把它当常数，又会漏掉一半以上的动态项。

**严谨形式（再给定义）**：记动作-观测位姿差为 `d_t = a^{ee}_t ⊖ o^{ee}_t`（位置取差向量，方向取单位向量夹角）。在 15 个任务上实测：

- 位置差均值 **13.3–20.0 mm**（总均值 16.5 mm），p90 **21.3–36.5 mm**；
- 方向差均值 **4.34°**（中位 2.82°，p90 7.66°）；
- 允许 2–3 帧超前对齐后，残差仍有 **10.3–17.3 mm**（均值 13.9 mm），说明「动作领先观测」只能解释一部分；
- 只减常数均值：RMS 从 **19.04 mm** 降到 **15.33 mm**（−20%）；
- 加入左右末端速度的线性模型 `d_t ≈ d_0 + J_v v_t + ε_t`：**R² = 0.502**，残差 RMS 降到 **10.82 mm**（−43%），部分任务 R² 超过 0.8。

所以姿态估计的正确对象不是「位姿本身」，而是三个关系量：**静态偏置 `d_0`、速度增益 `J_v`、剩余不确定度 `ε_t`**。动作表示应当把前两者消掉，只把 `ε_t` 留给闭环。

更妙的是，机体内部已经提供了一个**免费的自监督标定信号**：每个时刻左右手各有一个 EE 位姿，并同时给出 base 与 torso 两套坐标。用左右手两个对应点做 Kabsch，拟合 base→torso 刚体变换：

- 残差 **1.77–7.49 mm**（均值 4.09 mm）；
- 旋转角 **3.65–12.74°**（均值 9.93°），与腰部 pitch≈0.17 rad≈9.7° 吻合。

这说明机体位姿可以从**冗余的末端位姿**里被自校准出来，不需要外部动捕。姿态估计因此从纯视觉问题，扩展成了「视觉 + 本体冗余 + 任务结构」的联合估计问题。

### 1.3 合成：一个「关系估计」系统

两条灵感合成一个统一命题：

> **UniBot 的桌面操作 = 固定底座上的「关系估计」问题。**
> 需要估计三层关系：**机体关系**（base↔torso↔camera，可自校准）、**工具关系**（action↔observation 的位姿差，可自监督）、**物体关系**（物体↔夹爪，可在抓取-搬运过程中自监督）。估计出这三层关系，并在**场景相对坐标系**里输出动作，就能同时吃掉「底座放置偏移」与「位姿标定误差」。

据此提出本轮系统 **UniBot-PIVOT**（**P**ose-**I**nvariant **V**irtual-base **O**peration **T**ransform）：

- **BaseLock**：把 `pivot / lower_body / base` 锚定在首帧，身体是锚不是自由度；
- **PoseCalib**：用官方数据自监督拟合 `d_0` 与 `J_v`，在 action 与 observation 之间建立可逆校准；
- **SceneFrame**：episode 开始时用头部双目 + 本体估计桌面/物体坐标系，动作在场景相对坐标中表达；
- **PoseFromGrasp**：用「夹爪闭合 + 物体随动」自监督物体相对位姿与滑移标签；
- **VirtualBase**：只有在目标超出舒适工作空间时，才用有界腰部旋转做「虚拟底座」；
- **PoseGuard**：用机体/工具关系的残差做运行时一致性监测与降级。

## 2. 本轮对官方数据的定量核查

数据：`exp/duo_rows_cache/`，15/32 任务、91 episodes、42,800 帧、30 Hz。所有统计按 episode 分组、跨页边界排除。

| 观测 | 数值 | 对策略的含义 |
|---|---|---|
| 动作方差分解 | 手臂+夹爪 **99.91%**；pivot **0.002%**；lower_body **0.088%** | 「移动」是伪自由度；身体应冻结，不应让策略学习 |
| `pivot` episode 内 std | **1.25e-4**（最大 1.85e-3） | 底座在 episode 内完全静止 |
| `pivot` 跨 episode std | **2.82e-4**（最大 1.45e-3） | 同一任务的底座放置也几乎固定 → 训练分布不含底座偏移 |
| `waist` episode 内 std | **5.57e-3 rad**（最大 0.0102） | 腰部几乎不动；「虚拟底座」是外推，必须设信任域 |
| `lower_body` episode 内 std | **3.62e-3**（最大 6.34e-3） | 下肢是静态支撑；冻结近无损 |
| EE 工作空间（torso 系） | 半径均值 **0.357 m**；z 跨度 **0.154–0.335 m** | 桌面工作域窄；6 cm 的位移就是显著扰动 |
| base↔torso Kabsch 残差 | **1.77–7.49 mm**（均值 4.09 mm） | 机体位姿可自校准；提供免费监督 |
| 同帧 action-obs 位姿差 | 位置 **16.5 mm**（p90 28.2 mm），方向 **4.34°** | 位姿差与插入间隙同量级，是系统性瓶颈 |
| 最佳超前对齐 | 中位 **3 帧**；残差仍 **13.9 mm** | 不是纯延迟；静态/工具偏置真实存在 |
| 速度线性模型 | **R²=0.502**；RMS **19.04→10.82 mm** | 位姿差一半可由速度解释；应做动态校准 |
| 夹爪闭合帧占比 | 左 **21.3%** / 右 **22.2%** | 大量抓持期，可做自监督物体位姿 |
| 闭合 + 移动（搬运）帧占比 | 左 **12.1%** / 右 **11.9%** | 全量 169 h 数据里约有数百万帧搬运监督 |
| 腰部虚拟底座杠杆 | 10° 旋转 ≈ **6.22 cm** EE 位移 | 有杠杆，但训练分布仅 0.3°，必须保守 |
| 与 teaser 任务均值的 Spearman 相关 | 所有简单姿态/身体统计 \|ρ\|<0.32，p>0.25（n=15） | 不是「动得多就难」，而是「对得准才难」→ 精度才是主战场 |

**四条可执行结论**：

- **T1（移动是伪自由度）**：先冻结、再谈虚拟移动；把身体从动作空间里拿掉，降低维度与安全风险。
- **T2（姿态差是系统项）**：必须建模 `d_0` 与 `J_v`，并在动作表示里消掉；否则 `ee` 控制空间会被一个厘米级偏差毒化。
- **T3（泛化轴 = 场景关系）**：训练分布没有底座偏移，评测有；用场景相对动作表示去吸收，而不是让模型记忆绝对坐标。
- **T4（最难任务是位姿任务）**：teaser 榜最难的 Plug In Ethernet（17.7）、Unlock（20.1）正是插入/旋转/细对齐；本轮测到的 1.6 cm / 4° 位姿差与它们同量级，主火力应放在关系估计与相对位姿闭环，而不是更大主干。

## 3. 研究问题（本轮版）

- **Q1（底座冻结的边界）**：冻结 base/lower_body 是否在所有任务上近无损？是否存在必须依赖腰部/身体姿态的目标（高位、边角、身体外侧）？代价如何量化？
- **Q2（位姿差的分解）**：`d_t = d_0 + J_v v_t + ε_t` 能把位姿差解释到什么程度？剩余 `ε_t` 是多少，是否足以让插入类任务失败？能否用夹爪开合、负载、加速度进一步解释？
- **Q3（场景坐标系的估计精度）**：用头部双目 + 本体，在 episode 前 1 秒内估计桌面/物体坐标系，能达到多少 cm / 多少度？误差如何传播到成功率？
- **Q4（物体相对位姿的自监督）**：能否只用「夹爪闭合后物体随动」这一事实，学习物体相对夹爪的位姿与滑移，而不依赖物体 CAD 或人工 6D 标注？在未见物体上是否仍然有效？
- **Q5（虚拟底座的安全收益）**：腰部旋转的收益（10°≈6.2 cm）是否足以救回边角任务？在训练分布只有 0.3° 的情况下，多大的外推是安全的？

## 4. 设计原则

- **P1 先证伪再设计**：任何「移动/全身」创新必须先通过数据检验其必要性；不能证明有贡献的自由度一律不进动作空间。
- **P2 关系优先于绝对坐标**：策略输出/中间表示尽量用相对位姿、场景坐标、物体坐标；绝对坐标只作最后一层适配。
- **P3 标定与策略解耦**：`d_0`、`J_v`、base↔torso 变换是**可独立验证**的模块；标定器坏了，策略退回未标定形态，而不是整体失效。
- **P4 冻结优先、虚拟移动其次**：默认冻结身体；只有目标超出舒适工作空间且置信度高时才允许有界腰部动作。
- **P5 合规与可审计**：不读评测侧私有信息；不硬编码任务分支；所有降级与位姿异常可导出审计。
- **P6 单模型、单 checkpoint、单 API**：BaseLock / PoseCalib / SceneFrame / PoseFromGrasp 都在同一策略服务内，对外仍是 `metadata / get_action / reset`。

## 5. 最小可提交闭环（MVP）与退化链

**MVP = BaseLock（IP-01） + PoseCalib（IP-02） + SceneFrame（IP-03） + 通用 VLA 基线。**
理由：三者都不需要新数据、不改变官方接口，且直接针对本轮两条最大证据（身体是静态的、位姿差是系统性的）。PoseFromGrasp（IP-04）与 VirtualBase（IP-05）作为 P1，视代理评测结果推进。

**严格退化链**：

- Level-0：场景坐标系估计失败 ⇒ 退回 base 坐标系动作，保持基线行为；
- Level-1：位姿校准置信度低 ⇒ 退回未校准的绝对动作，但记录 `pose_gap` 告警；
- Level-2：腰部虚拟底座不可用/超信任域 ⇒ 退回「冻结腰部」；
- Level-3：姿态一致性监测触发 ⇒ 进入保守模式（减速、停止重估、必要时回退到开环 chunk）；
- Level-4：整条新链路失效 ⇒ 退回**纯基线策略**（永远保留一份能跑通的最小提交）。

## 6. 预期贡献（可验收）

1. **用数据证伪「移动操作」在本赛道的必要性**：给出身体自由度方差占比、底座静态性、冻结上界；把「不要动底座」从经验变成可复现的结论。
2. **量化并校准动作-观测位姿差**：给出 16.5 mm / 4.3° 的系统偏差、速度模型 R²=0.50、残差 RMS 10.8 mm；这是全赛道可复用的「位姿真相」诊断。
3. **给出一个可自校准的机体/工具/物体三层关系估计框架**：base↔torso 残差 4.09 mm，action↔observation 可自监督，物体相对位姿可在搬运中自监督。
4. **场景相对动作表示**：把「底座放置偏移」这个训练分布外变量从策略输入里消掉，直接服务 5 类泛化场景中的位置/背景/未见物体轴。
5. **一套低风险、可审计的提交**：BaseLock + PoseGuard + 降级链，对齐官方对延迟与动作规律性的可信度口径。

## 7. 本轮最大风险

**一句话**：本轮把赌注押在「姿态关系可被自监督估到厘米级、并把底座偏移归一化掉」上，而**最大的风险是评测端的底座/桌面关系与训练分布不同、且没有可靠的在线真值**——一旦场景坐标系估计在未见背景下偏了几厘米，场景相对动作会把原本正确的绝对动作也一起带偏，而且这种错误在 episode 内很难被察觉。

## 8. 下一轮迭代计划（深化与修剪）

- **深化**：把 PoseCalib 从线性速度模型升级为「速度 + 夹爪开合 + 负载」的条件模型；把 SceneFrame 与 VLA 的视觉 token 对齐（让策略直接看到场景坐标系，而不是后处理）。
- **修剪预案**：若 E701（位姿校准）在真机 A/B 上不能把插入类任务提升 ≥15%（相对），则**砍掉 `ee` 空间的一切精细标定**，只保留 BaseLock 与相对动作表示；若 E703（场景坐标系）在未见背景下误差 >2 cm，则退回 base 坐标系并只做数据增强。
- **保留项**：BaseLock、PoseGuard、以及「先证伪再设计」的方法论在任何情况下不砍。

## 0. 本轮结论摘要

**一句话路线**：先在数据上**证伪「移动」**，再把「姿态」拆成三层可自监督的**关系**：

**BaseLock（身体锚定） → PoseCalib（动作-观测位姿差） → SceneFrame（场景相对坐标） → PoseFromGrasp（物体相对位姿） → VirtualBase（有界腰部） → PoseGuard（一致性监测）**

**为什么是这个组合（四条本地量化证据）**：

| 证据 | 数值 | 推出的设计 |
|---|---|---|
| 动作方差分解 | 手臂+夹爪 **99.91%**；pivot **0.002%**；lower_body **0.088%** | 身体是静态锚；BaseLock（IP-01） |
| 同帧 action-obs 位姿差 | 位置 **16.5 mm**（p90 28.2 mm），方向 **4.34°**；速度模型 R²=**0.50**，RMS **19.04→10.82 mm** | 位姿差是系统项，必须动态校准（IP-02） |
| base↔torso Kabsch 残差 | **1.77–7.49 mm**（均值 **4.09 mm**），角度均值 **9.93°** | 机体位姿可自校准；用于场景归一化（IP-02/IP-03） |
| 闭合+搬运帧占比 | 左 **12.1%** / 右 **11.9%**（全量约数百万帧） | 物体相对位姿可自监督（IP-04） |

**合规红线（P5）**：单一 checkpoint、单一 API；不做「读题即硬编码」；不读取评测侧私有信息；所有新模块都可一键退化为基线。

## 2. 创新点详述

### IP-01 · BaseLock 身体锚定（P0）

- **动机**：15 个任务上，`action.pivot` episode 内 std 仅 **1.25e-4**、跨 episode **2.82e-4**；`lower_body` episode 内 **3.62e-3**；动作方差 **99.91%** 在手臂+夹爪。身体自由度在本赛道几乎是静态的；让策略学习它们只会把有限的数据与延迟预算浪费在常数上，并引入摔倒/越界风险。
- **与现有方案的差异**：常见做法是「全身动作一起回归」或「pivot 写 0」。前者把静态自由度当变量，后者可能在评测端破坏初始姿态。我们**读首帧身体状态并保持**，把身体作为**底座锚**；**策略只学习手臂+夹爪**，身体维度只做常数保持（若接口要求则发送首帧值；可选有界腰部）。
- **技术可行性**：极高。首帧 `observation.state.lower_body` / `waist_state_joint` 可读；`action.pivot` / `base_command` 若无必要可不发，或发首帧观测的保持值。
- **落地步骤**：①在 metadata 里限定只传必要 obs；②`reset()` 时缓存首帧身体状态；③`get_action` 里把 body 动作固定为 `ξ_0`（腰部默认 0 增量）；④用官方数据回放验证「冻结后动作与原始动作的 EE 偏差 ≤6 mm」；⑤真机 A/B：冻结 vs 学习身体。
- **风险**：某些任务可能需要腰部/身体姿态（高位、边角）。缓解：**零成本探测**（先只读不发，观察基线是否已用身体）；若确实需要，转 IP-05 的有界虚拟底座，而不是放开全身。

### IP-02 · PoseCalib 动作-观测位姿校准（P0）

- **动机**：同帧 `action.*_ee_pose_*` 与 `observation.state.*_ee_pose_*` 存在 **16.5 mm / 4.34°** 的系统差（p90 28.2 mm）；允许 2–3 帧超前仍剩 **13.9 mm**。这个量级与插入任务间隙同量级。把它当噪声，`ee` 控制空间会被毒化；当常数，只能解释 20%。
- **与现有方案的差异**：现有方案直接用 action 位姿做监督或直接预测绝对位姿；我们把位姿差拆成**静态偏置 + 速度项 + 剩余不确定度**，并用官方数据自监督拟合：
  `d_t = a^{ee}_t ⊖ o^{ee}_t ≈ d_0 + J_v v_t + ε_t`，
  实测 `R²=0.502`，RMS 从 **19.04 mm** 降到 **10.82 mm**；若再按 task/侧别拟合，可进一步下降。
- **技术可行性**：高。`action` 与 `observation` 都在官方数据里，无需新标注；闭式最小二乘即可得到 `d_0, J_v`，也可用 2 层 MLP 条件在速度/夹爪开合/负载上。
- **落地步骤**：①按 episode 对齐 action/obs，排除 reset 边界；②拟合全局/分任务/分侧别的 `d_0, J_v`；③对比常数、速度、速度+夹爪、非线性四档；④把校准器接在 `ee` 动作头与执行器之间（或用它把 action 位姿转成一致的 obs 位姿做辅助损失）；⑤用留出 episode 测 RMS 与 p90。
- **风险**：校准器可能过拟合任务/速度分布；在极慢速（静态偏置主导）与极快速（动态项主导）两端误差不同。缓解：分速度段评估；对 `ε_t` 输出置信度，低置信时退回未校准动作并告警。

### IP-03 · SceneFrame 场景相对动作表示（P0）

- **动机**：训练数据的底座放置几乎固定（pivot 跨 episode std **2.82e-4**），但评测在 N 台真机上运行，机器人相对桌面的放置不可能一致；5 类泛化场景中的「位置」也包含全局偏移。若策略记忆 base 系绝对坐标，这些偏移会直接变成分布外输入。
- **与现有方案的差异**：常规做法是「域随机化 + 大模型硬吃」；我们改为**几何归一化**：episode 开始时用头部双目 + 本体估计一个桌面/物体场景坐标系 `F_s`，把动作与观测都表达在 `F_s` 中。底座偏移在 `T_sb` 里被显式吸收，策略看到的是「物体在桌上哪里」，而不是「关节在 base 系哪里」。
- **技术可行性**：中–高。头部有两路相机（可做双目深度）；`state_d435` / `state_torso` 提供相机/躯干位姿；EE 位姿提供尺度与一致性校验。桌面是平面，RANSAC 拟合稳定；物体簇可用深度 + 颜色分割。
- **落地步骤**：①双目校正 + 深度/点云管线；②RANSAC 桌面平面 → 定义 z-up 与桌面原点；③目标物体簇分割 → 场景系原点/轴向；④用 `state_torso` / `state_d435` 把点云转到 torso/base 系；⑤动作头输出 `ã = T_sb a`，执行时反变换；⑥用左右 EE 的 Kabsch 残差做健康检查。
- **风险**：未见背景、反光桌面、透明物体可能导致平面/物体估计失败。缓解：多帧 RANSAC + 置信度门控；失败即退回 base 系（Level-0），不阻塞基线。

### IP-04 · PoseFromGrasp 抓取-搬运自监督物体位姿（P1）

- **动机**：物体 6D 位姿标注昂贵，官方数据也没有逐帧物体 pose。但数据里**闭合+搬运帧占 12%**（左 12.1%/右 11.9%）；在这段窗口里，若物体被夹稳，它相对夹爪的位姿应近似不变；若滑移，则会变化。这给出一个免费的**相对位姿/滑移**监督信号。
- **与现有方案的差异**：现有方案依赖物体 CAD / 人工 6D 标注 / 大规模仿真；我们利用机器人自己的**抓取-搬运**作为自监督任务：用腕部相机跟踪物体特征，约束其在夹爪系中的位姿在刚体搬运段保持不变，变化即滑移。
- **技术可行性**：中。需要图像与光流/特征跟踪；官方数据有左右腕相机，适合做相对位姿。无 CAD 也可做「相对」而非「绝对」位姿。
- **落地步骤**：①用夹爪开合 + EE 速度切出搬运窗口；②腕部帧做特征跟踪/光流；③以「夹爪系中物体位姿恒定」为损失训练相对位姿编码器；④滑移检测：位姿变化超过阈值即标记；⑤把相对位姿 token 送入策略，服务插入/对齐。
- **风险**：纹理弱/透明/反光物体跟踪失败；搬运窗口里夹爪可能微动。缓解：只用高置信窗口；与 IP-02 的 EE 位姿校准联合；在未见物体上做留出评估。

### IP-05 · VirtualBase 有界腰部虚拟底座（P1）

- **动机**：底座冻结后，唯一可用的「移动」是腰部/躯干。实测腰部 10° 旋转在 `r≈0.357 m` 处产生 **6.22 cm** EE 位移（范围 5.87–6.62 cm），相当于工作空间 z 跨度（0.154–0.335 m）的 20–40%。这对边角/高位目标是真实杠杆。
- **与现有方案的差异**：常规要么完全冻结身体，要么让全身策略自由输出；我们做**有界虚拟底座**：默认 0，只在目标超出舒适工作空间且置信度高时，输出 ≤3° 的腰部增量，并用信任域与回滚保护。
- **技术可行性**：中。需要可达性估计与腰部方向符号；训练数据腰部运动只有 0.3°，属于外推，必须先在仿真/低增益真机上验证。
- **落地步骤**：①从场景系估计目标位置与舒适工作空间边界；②计算所需腰部增量 `δξ` 并截断到 `[-3°,3°]`；③用 IK/雅可比把手臂补偿到同一 EE 目标；④限制角速度与加速度；⑤失败即回 0；⑥真机小步试探。
- **风险**：外推导致身体失稳或评测端不跟踪腰部；收益可能为 0。缓解：默认关闭；一次零成本探测后再决定；最大增量与速率双限。

### IP-06 · PoseGuard 关系一致性安全阀（P1）

- **动机**：底座被碰、编码器滑移、相机松动都会让「关系估计」失效；而这类故障在 episode 内不会自己暴露。官方又明确会看延迟/动作规律性等可信度信号，可审计性是相对优势。
- **与现有方案的差异**：多数提交只做动作限幅；我们把**机体关系**变成运行时统计量：每帧用左右 EE 在 base/torso 两系的对应点做 Kabsch，残差 `r_t` 若连续超过阈值（如 >15 mm 或 >3σ）则判定关系异常。
- **技术可行性**：高。纯本体计算，无额外传感器；残差基线 1.77–7.49 mm，阈值可标定。
- **落地步骤**：①在线 Kabsch（2 点 + 历史窗口）；②残差 EWMA 与阈值；③异常时进入保守模式（减速/停止重估/回退开环）；④记录审计日志（残差、位姿差漂移、降级次数）。
- **风险**：正常快速运动可能让残差瞬时变大 → 误报。缓解：用时间平滑 + 连续帧确认；阈值由数据分布定；误报只触发保守而非急停。

### IP-07 · PoseAug 位姿-only 增强（P2）

- **动机**：底座偏移是训练分布外变量；不必重渲染图像，只需对 EE/场景坐标做随机刚体变换，就能让策略见到「同一视觉、不同坐标」的样本。
- **做法**：训练时对 `p_ee`、场景系目标、相对位姿施加随机 `SE(3)` 扰动（平移 ±5 cm、旋转 ±5°），图像不变；同时保持动作的物理一致性（用 `T_sb` 变换）。
- **风险**：图像与位姿不一致可能教坏模型 → 只作为辅助正则，权重小；用留出集验证不伤干净性能。

## 3. 符号与定义（U1–U12）

| 符号 | 含义 |
|---|---|
| `π` | 策略：观测 + 语言 → 动作块（单一 checkpoint） |
| `ξ_t` | 身体状态（pivot / lower_body / waist） |
| `ξ_0` | episode 首帧身体状态（锚定值） |
| `d_t` | 动作-观测 EE 位姿差 `a^{ee}_t ⊖ o^{ee}_t` |
| `d_0, J_v` | 位姿差的静态偏置与速度增益 |
| `T_bt` | base→torso 刚体变换 |
| `F_s` | 场景坐标系（桌面/物体） |
| `T_sb` | base→scene 刚体变换 |
| `ã_t` | 场景相对动作 `T_sb a_t` |
| `o^g_t` | 物体在夹爪系中的相对位姿 |
| `m_t` | 可达性余量（目标到舒适工作空间边界的距离） |
| `r_t` | Kabsch 关系一致性残差 |
| `δξ` | 有界腰部虚拟底座增量 |

**定义 U1（身体锚定策略）** `π(a | o, ℓ) = π_arm(a_arm, a_grip | o, ℓ) ⊗ δ_{ξ=ξ_0}`，即策略只在手臂+夹爪上输出，身体固定为首帧值。若启用虚拟底座，则 `ξ_t = ξ_0 + δξ_t`，`‖δξ_t‖ ≤ δ_max`。

**定义 U2（动作-观测位姿差）** `d_t = (p^{a}_t - p^{o}_t, angle(R^{a}_t, R^{o}_t))`，其中 `p` 为位置，`R` 由官方方向向量按单位化后的夹角近似。

**定义 U3（位姿差模型）** `d_t ≈ d_0 + J_v v_t + ε_t`，`v_t` 为末端速度；`ε_t` 为剩余不确定度，带协方差 `Σ_ε`。

**定义 U4（校准动作）** 给定策略输出的目标 `a^{ee}`，执行前校正为 `â^{ee} = a^{ee} - (d_0 + J_v v_t)`；若 `ee` 空间不使用，则用其构造辅助一致性损失。

**定义 U5（机体关系估计）** `T_bt = argmin_{R,t} Σ_{s∈{L,R}} ‖R p^s_b + t - p^s_t‖²`（Kabsch），残差 `r_t` 定义为该最小二乘的均方根。

**定义 U6（场景坐标系）** `F_s = (O_s, R_s)`，由桌面平面法向、桌面原点与目标物体主轴确定；`T_sb` 把 base 系点变到场景系。

**定义 U7（场景相对动作）** `ã_t = T_sb · a_t`；执行时 `a_t = T_sb^{-1} · ã_t`。

**定义 U8（场景相对误差）** `e_s = ‖T̂_sb - T_sb‖`（平移 cm / 旋转 deg），用于门控。

**定义 U9（物体相对位姿）** `o^g_t = T_{gripper,t}^{-1} · T_{object,t}`；在刚体搬运窗口内应近似常数。

**定义 U10（滑移指标）** `σ_t = ‖o^g_t - o^g_{t-1}‖`；超过阈值即判滑移。

**定义 U11（虚拟底座）** `δξ_t = clip(δξ^*_t, -δ_max, δ_max)`，`δξ^*` 由场景系目标的可达性余量 `m_t` 推出；`δ_max=3°`（初始）。

**定义 U12（降级状态机）** `state ∈ {NORMAL, CONSERVATIVE, FALLBACK}`；由 `r_t`、`e_s`、位姿差置信度共同驱动，任何异常只降级、不放大动作。

```python
            "token": os.environ["UNIBOT_SUBMISSION_TOKEN"],
        }

    # ---------- episode 生命周期 ----------
    def reset(self, port=None):
        s = self.sessions.setdefault(port, Session())
        s.clear()
        s.state = "NORMAL"

    def get_action(self, obs, port=None):
        s = self.sessions[port]
        t0 = time.perf_counter()

        # 0) 首帧：锚定身体（IP-01）
        if s.xi0 is None:
            s.xi0 = {
                "lower_body": obs["observation.state.lower_body"][-1],
                "waist":      obs["observation.state.waist_state_joint"][-1],
            }

        # 1) 场景坐标系（IP-03）；失败则退回 base 系
        if s.T_sb is None or s.reestimate:
            s.T_sb, s.scene_conf = self.scene.estimate(obs)
            if s.scene_conf < SCENE_CONF_MIN:
                s.T_sb = np.eye(4); s.state = "CONSERVATIVE"

        # 2) 机体关系健康检查（IP-06）
        r = self.guard.residual(obs)                 # Kabsch 残差 (mm)
        s.guard_ewma = 0.9 * s.guard_ewma + 0.1 * r
        if s.guard_ewma > GUARD_THRESH_MM:
            s.state = "CONSERVATIVE"                 # 只降级，不急停

        # 3) 虚拟底座（IP-05，默认关闭）
        dxi = np.zeros(3)
        if ENABLE_VIRTUAL_BASE and self.reach_failed(obs, s.T_sb):
            dxi = self.virtual_base(obs, s.T_sb, s.xi0["waist"], self.delta_max)

        # 4) 场景相对动作（IP-03）
        a_scene = self.model.act(obs, scene=s.T_sb, body_anchor=s.xi0, waist_delta=dxi)

        # 5) 位姿校准（IP-02）：在接口处消掉 d0 + Jv v
        a_exec = self.calib.uncorrect(a_scene, obs, s.T_sb)

        # 6) 组装动作：只发必要维度（IP-01）
        out = self.pack(a_exec, s.xi0, dxi, obs)

        # 7) 审计与降级（IP-06 / U12）
        out = self.guard.audit(out, obs, s, t0)
        s.last_action = out
        return out

    def pack(self, a, xi0, dxi, obs):
        return {
            "meta.token": os.environ["UNIBOT_SUBMISSION_TOKEN"],
            "action.left_arm":  a["left_arm"].astype(np.float32),
            "action.right_arm": a["right_arm"].astype(np.float32),
            "action.left_gripper":  a["left_gripper"][:, None].astype(np.float32),
            "action.right_gripper": a["right_gripper"][:, None].astype(np.float32),
            # 默认保持首帧身体；若接口要求 pivot/lower_body，则发锚定值
            "action.pivot": np.tile(xi0["pivot"], (len(a["left_arm"]), 1)),
            "action.lower_body": np.tile(xi0["lower_body"], (len(a["left_arm"]), 1)),
        }
```

```python
def grasp_relative_pose(episode, gripper_closed, ee_speed):
```

## 5. 推导（引理 L1–L7）

**引理 L1（冻结身体近无损）** 设身体状态在 episode 内相对首帧的偏离为 `δξ`，末端位置对身体的雅可比范数为 `L_ξ`。若策略把 `ξ` 固定为 `ξ_0`，则诱导的末端偏差满足 `‖Δp_ee‖ ≤ L_ξ·δξ`。在本数据上 `δξ_waist ≤ 0.0102 rad`、`δξ_lower` 的逐维 std ≤ 0.0063，取 `L_ξ ≈ r = 0.357 m/rad`，得 `‖Δp_ee‖ ≲ 6 mm`；该值小于本轮测到的动作-观测位姿差 16.5 mm，也小于插入类任务需要闭合的厘米级误差。故冻结身体在统计上近无损（例外需 IP-05 单独处理）。∎

**引理 L2（位姿差的偏差-方差分解）** 记位姿差随机向量 `d`。有 `E‖d‖² = ‖E d‖² + tr Cov(d)`。用全局常数均值校正只移除 `‖E d‖²`；本数据中原始 RMS 为 19.04 mm，常数校正后 15.33 mm，说明静态均值只解释约 20%。加入速度项后 RMS 降到 10.82 mm，`R²=0.502`，即约 50% 的方差可由速度解释。因此一个仅含常数的「工具偏置」模型是不够的；校准器必须条件于速度（进一步可条件于夹爪开合/负载）。∎

**引理 L3（场景相对表示的底座不变性）** 设底座放置变化为刚体变换 `G`（base 系左乘），观测/动作都随之变换。若动作表示为 `ã = T_sb a`，且 `T_sb` 同步更新为 `T_sb G^{-1}`，则 `ã` 不变。因此策略在场景相对坐标中看到的输入与底座放置无关；剩余误差仅来自 `T_sb` 的估计误差 `e_s`。一阶上，末端位置误差 `‖Δp‖ ≤ ‖e_s‖ + ‖p‖·‖δR_s‖`。这直接解释了为什么 IP-03 的精度目标设为 ≤1 cm / ≤2°：在 `p≈0.36 m` 时，2° 对应约 12.6 mm，已接近可接受上限。∎

**引理 L4（虚拟底座的杠杆与信任域）** 腰部旋转 `δθ` 时，半径 `r` 处的 EE 位移近似 `2r·sin(δθ/2)`。取 `r=0.357 m`、`δθ=10°`，得 6.22 cm；但训练数据中 `δθ` 的 episode 内 std 仅 0.0056 rad≈0.32°，因此 10° 是约 30× 外推。为把外推误差控制在 1 cm 内，取 `δ_max=3°`（对应 1.87 cm）并用信任域、速度限幅与回滚；只有在 `m_t>0` 且场景置信度高时才启用。∎

**引理 L5（关系一致性可检测性）** 两个 EE 的 base/torso 坐标给出 12 个标量约束，而 `T_bt` 只有 6 个自由度 ⇒ 系统超定，正常残差为 1.77–7.49 mm（均值 4.09）。若底座被碰 3 cm 或躯干偏 2°，残差的期望增量约为 `O(‖Δp‖)`，即 20–30 mm，超过正常残差 3–5 倍；用 EWMA + 连续帧确认可在误报 <1% 下达到 AUROC ≥0.9。∎

**引理 L6（抓取-搬运自监督的可识别性）** 在刚体搬运窗口内，若夹爪闭合且无滑移，则 `o^g_t = T_g^{-1}T_o` 为常数。于是「`o^g` 的变化」要么是滑移，要么是跟踪误差；在滑移稀疏的假设下，最小化窗口内 `o^g` 的时序方差即可学到相对位姿（至多一个常数偏置，可由首帧锚定）。若滑移频繁，则该假设失效，应退化为「相对位姿 + 滑移检测」而非绝对位姿。∎

**引理 L7（机体标定的样本复杂度）** 用 `T` 帧、每帧 2 个 EE 点做 Kabsch，估计误差随 `1/√T` 下降；本数据每 episode 数百帧，实测残差已降到 1.77–7.49 mm，说明单 episode 内即可完成自校准。跨 episode 合并可进一步降噪，但会引入底座变化的偏差 ⇒ 应在**每个 episode 内单独估计** `T_bt`，而不是全任务一个常数。∎

| **多点位/多端口并发导致场景估计串扰** | 中 | 高 | 每端口独立 session；估计器无全局状态；压测 8 h |

| **过度依赖官方 data 的固定底座** | 中 | 中高 | 显式做底座偏移增强（PoseAug）与场景相对表示 |
