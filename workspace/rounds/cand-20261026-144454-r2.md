# 第 8 轮（灵感循环第 2 轮）· GEO-ARM：把标定变成 3D token，把主辅臂变成控制量

> 检索/复核日期：2026-10-26（UTC）。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型、选手自部署 + 官方远程真机 API。状态文件上一轮是第 7 轮；你把这轮叫灵感循环第 2 轮，我保留跨轮谱系，写成第 8 轮（灵感循环第 2 轮）。本轮灵感词是「视觉编码器」「机械臂」「创新点挖掘」。我先各自钉到本轮核实到的官方事实上，再合成主判断：**在成功率优先的排名下，最值得押注的不是继续抠步骤分，而是用官方免费标定把视觉编码器升级成“标定感知的度量 3D token”，先消灭位置/背景/遮挡/未见物品四类“轴零点”；机械臂侧用“动态主辅角色 + 关节空间 chunk-delta + 跟踪残差接触回路”承接；创新点挖掘本身则做成“轴切片矩阵 + 探针套件 + 成本/收益排序”的可执行流程。** 第 7 轮 PILOT 的放置闭环不作废，但目标函数从“抢步骤分”改写为“把放置变成成功转换器”。

## 0. 本轮先核实：排名规则改了，一切都要重算

### 0.1 官方手册：成功率优先，步骤分只是 tiebreaker

官方参赛手册（中英文两版，飞书文档）在“排行榜与评分”一节的要点是：**实时榜单按 32 个任务的总平均成功率排序；成功率相同时，按总平均步骤分排序；若仍相同，提交日期较早的模型排序靠前** [S12][S13]。同一份手册还写明：每个任务评测 **10 次**，覆盖 **5 类泛化场景、每类 2 次**，单次限时 **180 秒** [S12][S13]。

这条事实推翻了第 7 轮的主目标函数。第 7 轮把“终局步骤分 39.8% / 放置类步骤 59.7%”当作第一性依据，逻辑是“步骤分是主分、成功率是闸门”；现在反过来了：**成功率是唯一主分，步骤分只在成功率并列时使用，再并列才看提交日期。** 第 7 轮的 SSG / PGL / OPT / SVL 不是没用，但它们的目标函数要改写：

- SSG：从“抢步骤分”变成“成功门控 + 防假完成 + 失败诊断”。
- PGL / OPT：从“提步骤分”变成“提全任务成功率”。
- SVL：从“终局加分”变成“成功转换器”（释放失败时修复）。
- ICR：从“检索轨迹提步骤分”降为“相位/位姿先验的次级组件”。

这不是措辞变化，而是预算变化：任何“只提步骤分、不提成功率”的工作，本轮默认不做。

### 0.2 每个任务 10 次 = 5 轴 × 2 次；每个轴 20%

由 0.1 可直接推出本轮最锋利的算术事实：

- 每个任务的分数 = 10 次里成功的次数 / 10。
- 10 次 = 5 类泛化 × 每类 2 次，所以**每一类泛化恰好占该任务 20%**。
- 若某任务在 4 类上 100%、在 1 类上 0%，该任务得分 **80%**，不是 0%，也不是 100%。
- 把某一类从 0% 修到 100%，该任务 +20pp；摊到 32 个任务，**+0.625pp 总分**。
- 把同一类在 32 个任务上都从 0% 修到 100%，**总分 +20pp**。
- 把所有轴均匀抬升 10pp（例如 50%→60%），**总分 +10pp**。

所以：**消灭一个轴零点的杠杆，是“所有轴各抬 10pp”的 2 倍。** 一个任务在某一轴上 0%，是一个结构化、可定位、可修复的洞；一个任务在五轴上都是 60%，是一个弥散问题。前者便宜，后者贵。第 7 轮的“放置是唯一跨轴杠杆”仍然成立（放置失败会在所有轴上杀死成功），但它不是唯一的**结构化**机会：**感知轴上的零点是更大、更可识别的机会**，而视觉编码器正是同时打位置/背景/干扰物/未见物品四轴的工具。

这也是“榜首成功率不到 30%”这类传闻的正确用法：如果它大致为真，说明大量任务在某一轴上直接归零，而不是五轴均匀 30%。**先找零点，再抬地板。**

### 0.3 官方数据里已经有“免费标定”

我重新抓了 HangCup 数据集的 `meta/info.json` [S4]，确认本轮最关键的新事实：**官方数据不只有 RGB，还带完整相机参数。**

- `camera_params.head_stereo`：左右相机内参、畸变系数、相对旋转 `R`、平移 `T`，且 `rectified: true`。实测 `fx≈282.37/281.87`，基线 `|T_x|≈58.25mm`，`T_y≈-0.17mm`，`T_z≈0.58mm`，`R≈I`（已校正）。
- `camera_params.wrist_left/right`：彩色相机 `fx≈436.4/435.1`、640×480、`inverse_brown_conrady` 畸变；还有 IR1/IR2 内参与 IR 基线（约 18mm）。腕部是 RealSense 级相机，但提交 API 只发 RGB。
- `features`：`head_stereo_left/right`、`wrist_left/right` 四路视频；`state_torso[6]`、`state_d435[6]`、双臂 EE 位姿（base 与 torso 两套）、`waist_state_joint[3]`、`lower_body[15]`、左右腿 `[6+6]`、`recomputed_ee_valid`。
- HangCup 规模：**1,043 episodes / 194,564 frames / 30fps**，`lastModified` 为 **2026-10-14** [S4]。

**含义**：度量 3D 的监督是免费的——头部双目给深度，腕部给近景，URDF/数据集给相机与末端的外参链。我们不需要买深度相机，也不需要先建高保真仿真。缺的不是数据，而是**一个能用上标定、且在双目失效时不会崩的编码器**。

### 0.4 接口的自由度与三个未核实

提交接口 v2 的观测/动作目录 [S6] 和参考环境 [S6] 给出：

- 观测：四路 RGB（`cam_left_high` / `cam_right_high` / `cam_left_wrist` / `cam_right_wrist`，480×640×3 uint8）、双臂关节（7）、双臂 EE 位姿 base（6）、夹爪（1）、下半身（15）、语言（str）。
- 动作二选一：**joint** = `action.left_arm(7)+right_arm(7)+left_gripper(1)+right_gripper(1)+action.pivot(7)`；**ee** = 双 EE pose(6)+双夹爪(1)+`action.pivot(7)`。
- `action.pivot` 7 维命名是 `vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height`；数据集里另有 `action.base_command[4]`、`action.lower_body[15]`、`action.waist_action_joint[3]`，所以 pivot 很可能混合了底盘/腰/高度，但**语义未核实**。
- `metadata` 由我们声明：`control_space`、`obs_delta_indices`、`image_resize`、`action_chunk_size`、`token`。动作按 chunk 校验，形状是 `(H, dim)`；参考客户端每次 `get_action` 后 `env.step` 一次，暗示评测器按 chunk 消费。
- 图像在传输时 JPEG q95 / subsampling 0 压缩；数据集视频是 AV1。**训练/推理存在压缩域差**。
- 30 步 chunk @30Hz ≈ **1 秒决策预算**，不是第 7 轮假设的“p99 < 100ms/step”。这放宽了视觉编码器的延迟约束，但也意味着**每 1 秒只能看一次**，chunk 内的开环质量很重要。

三个必须在调试槽核实的接口问题：

1. `cam_left_high/right_high` 是否就是数据集里那对**已校正双目**？如果 API 送的是原始未校正图，`camera_params` 的 `R/T/rectified` 不能直接搬。
2. `action.pivot` 的 7 维到底控制什么？底盘？腰？高度？如果是 no-op，必须保持上一条命令；如果控制腰，则是 T15/T16/T09 等腰部运动任务的关键。
3. 评测器是**每 chunk** 调一次 `get_action`，还是每步调一次但只执行 chunk 的第一帧？这决定异步流水线和重规划频率。

在核实前，方案必须带 fallback：双目不对齐→单目深度；pivot 不明→hold；chunk 消费不明→按 1 秒 chunk 做异步。

### 0.5 榜单仍是占位，“榜首 <30%”不可核实

截至 2026-10-26，`leaderboard.html` / `leaderboard_data.json` / `runs.html` 仍是 Coming Soon / 占位 [S9][S10]。公开渠道没有 UniBot 真实榜单。第三方聚合站 Wizwand 列出 “Unitree G1 Dex1 (test)” 的 SOTA 平均成功率 28（6 条结果），但底层页面不可访问，**只能标“未核实”** [S31]。

可用的外部锚点：

- RoboChallenge Table 30 V2 榜首 **43.33%** 成功率 / **56.80** 分 [S32]。
- CVPR 2026 RoboChallenge 榜首 **40.89%** [S33]。

如果 UniBot 榜首确实 <30%，它比 RoboChallenge 更难，原因很可能是 32 任务广度 + 5 轴泛化 + 真机远程，而不是单一任务难度。这反而强化“轴零点优先”的判断：**不要假设均匀 30%，要假设“大部分任务接近 0、少数任务很高”的肥尾分布。**

### 0.6 视觉编码器的证据已经足够，但都绕开了“真实标定 + 可靠性”

- **StereoVLA**（arXiv 2512.21970v2）：GeoSem 编码器 + FoundationStereo + 交互区域深度 + 相机参数估计；真机 +33.4% 绝对提升 [S16]。它证明双目几何有用，但它**估计**相机参数、用合成双目，且没有处理“双目在透明/反光物体上失败”。
- **ExStereo**（arXiv 2610.04805）：在 π0.5 / SmolVLA 上加双目 mid-training 和 action-stereo cross-attention；双臂 PiPER [S17]。它证明双目能接进 VLA，但它是训练配方，不是可靠性感知编码器。
- **StereoPatch**（arXiv 2609.15509）：DINOv3 + 深度基础模型，patch 级 RGB-D 融合，冻结编码器，六个真机任务 [S18]。它证明 patch 级融合有效，但假设有干净深度。
- **DEM**（arXiv 2609.18374）：微调 DINOv3 ConvNeXt-B + NeoBERT + MeanFlow；55.6% vs 冻结 32.6%，8–17× 更快 [S19]。它证明小型解耦策略可以打赢冻结 VLM，但不用双目。
- **R²-WAM**：DINOv3 比 VAE-only +9.3pp；通用表征 82.2% vs 专用 80.0%；未来特征预测 [S20]。它支持 DINOv3 和轻量世界模型。
- **MAPS**：DINOv2 保留几何先验优于 SigLIP；早层语言优于晚层 [S21]。它支持“冻结语义教师 + 几何通路”的双路设计。
- **PAVE**：VLA 微调会**类别不对称地**破坏 affordance（尤其 cut/support），297K adapter 可恢复 [S22]。它警告不要端到端微调语义编码器。

**空白很清楚**：没有工作同时做到（a）用真实、已校正的双目；（b）对透明/反光/细长物体做可靠性门控；（c）用头部双目蒸馏腕部单目度量深度；（d）输出 base 系 3D token 而不是相机系特征；（e）保留冻结语义通路防 affordance 退化。**这正好是 UniBot 的设定，也是本轮的视觉编码器创新点。**

### 0.7 机械臂的证据：主辅角色、关节空间、接触残差

- 双臂不是边角：32 个任务里 20+ 个双手 gripper 都活跃；HangCup 左 gripper 均值 **4.46**、右 **2.37**（开度分布明显不对称，具体角色需看视频）；强不对称任务还有 SpellRobot / PickOutBatteries / PourOutMedicine / OrganizeBookshelf [S2][S4]。
- **PA-BiCoop**（arXiv 2606.28192）：动态主辅臂角色分配，RLBench2 +48%、真机 +50% [S23]。它证明“谁主谁辅”是独立于视觉的杠杆。
- **BiRoAD**（arXiv 2609.23445）：swap-symmetric / antisymmetric 分解，无标签角色自适应 [S24]。它支持从数据学角色，而不是硬编码左右。
- **BUDS / Stabilize to Act**：稳定臂 + 操作臂，20 条演示达 76.9%。它支持“一手稳住、一手操作”的范式。
- **Brace Yourself**（arXiv 2609.25486）：G1 支撑手 60N vs 13.5N；任务条件化 bracing [S25]。它证明 G1 的支撑臂可以真用力。
- **CoPRE**（arXiv 2609.27381）：G1 本体感觉接触检测，82.2% recall、5.5N，用关节力矩残差 [S26]。它证明没有力传感器也能感知接触。
- **Blind Dexterity**（arXiv 2608.29487）：G1 纯本体感觉，跟踪残差 `e_t = q_des − q_t` 是接触信号 [S27]。这是最便宜的接触信号。
- **Action Space Design**（arXiv 2602.23408）：delta 优于 absolute；同体、数据足时 joint-space 优，跨体/泛化时 task-space 优 [S28]。UniBot 是同体、33k 演示 → **joint-space chunk-delta 是默认**。
- **ER action space**（IEEE RA-L 2024）：冗余感知动作空间改善受限空间控制；G1 臂 7-DOF，肘部 swivel 在书架/盒子任务里重要 [S30]。

**空白**：没有工作把“动态主辅角色 + joint-space chunk-delta + 跟踪残差接触 + 冗余 token”合到一个 humanoid VLA 里，并在 UniBot API 下验证。PA-BiCoop 是固定本体双臂；CoPRE 是接触检测不是策略；动作空间研究不是双臂。**这是本轮的机械臂创新点。**

### 0.8 数据规模与外部数据

- 官方 32 数据集约 **33k episodes / 169h**；HangCup 1,043 条 / 194,564 帧 [S3][S4]。
- 宇树另有 72 个 G1 Dex1 数据集（Hang_Keys、Pour_Drink、Assembling_Motor、Two_Robot_Clean_Table 等），同本体，可能可用于预训练 [S36]。但参赛手册渲染到 2.2「比赛资源」就被截断，**外部数据/预训练权重规则未读全**，默认 OFF。
- 官方 32 数据集对 GEO 足够：32 任务 × 200 条 = 6,400 条（约 20%）即可做几何预训练；策略训练再用全量。

## 1. 三个灵感词，各自钉到事实上

### 1.1 视觉编码器：不是换 backbone，是把“标定”变成监督

第 7 轮的视觉栈是“Qwen2.5-VL 的语义 token + 2D 锚点”。它强在语义，弱在度量：语言能定位“杯子”，但“杯把在 3D 里的朝向、离桌沿 2cm、腕部从哪个角度合拢”全靠策略隐式学。UniBot 的评分又恰好卡在这些度量量上：插入、堆叠、挂杯、拉拉链、拧瓶盖。

本轮的正确升级不是“把 SigLIP 换 DINOv3”这么简单，而是三件事：

1. **用官方标定做度量监督**：头部双目 → 深度/点图；腕部单目 → 用头部双目做跨视角蒸馏；URDF + EE 位姿 → base 系点图。这样 encoder 的输出是**米制**的，不是“看起来像”的特征。
2. **可靠性门控**：透明药瓶、金属锁、试管、拉链、注射器会让双目匹配失败。StereoVLA/ExStereo 都假设双目可用；我们要显式预测 `reliability`，低可靠时回退到语义/本体/单目先验。这是与现有双目 VLA 的**第一差异**。
3. **base 系 3D token + 冻结语义双路**：策略看到的不是“左相机第 37 个 patch”，而是“base 系里杯把前方 8cm 的一个 3D token，可靠度 0.9”。这让位置/背景/干扰物轴的变化不再改变 token 的物理含义；同时用冻结 DINOv3/SigLIP 防 PAVE 式 affordance 退化。

一句话：**第 7 轮把视觉当“语义定位器”；本轮把视觉当“带误差棒的度量传感器”。**

### 1.2 机械臂：不是 14 个关节，是“主辅角色 + 接触回路 + 冗余”

第 7 轮的动作空间默认 EE（末端位姿），理由是“跨任务统一、易做放置”。但本轮核实到两件事，必须修正：

- 数据集的主动作字段（`action.left_arm/right_arm`）是**关节位置**（同时也有 EE 位姿字段），且 7-DOF 臂的冗余姿态（肘部）在书架/盒子/背包任务里直接决定碰撞 [S4][S30]。
- 2026 年的动作空间研究给出明确结论：同体、数据足时 joint-space 优于 task-space；delta 优于 absolute [S28]。UniBot 是同体、33k 演示，**没有跨体需求**。

所以本轮默认 **joint-space chunk-delta**：内部预测 `Δq`，输出绝对关节目标 `q_t + Δq`（API 要绝对关节）。EE 只作为 PGL/OPT 的内部目标，最后 IK 到关节；如果调试槽发现 joint 跟踪差，再回退 EE。

机械臂的第二个升级是**主辅角色**。UniBot 很多任务是“一手稳住/扶住，一手操作”：HangCup 左右开度 4.46/2.37，角色明显不对称；SpellRobot 一手扶板、一手放字母；PickOutBatteries 一手扶盒、一手挑电池（具体角色以视频为准）。固定左右分工不够，因为同一任务的不同阶段角色会换。PA-BiCoop/BiRoAD 证明动态角色是独立杠杆 [S23][S24]；我们把它做成一个 **role token**，让策略每个 chunk 重新决定主辅，辅臂动作在主角系里表示。

第三个升级是**接触回路**。插入/拧/拉拉链/注射器是接触密集任务，但 API 没有力传感器。CoPRE/Blind Dexterity 证明 `q_des − q_t` 的跟踪残差可以作为接触代理 [S26][S27]。我们把残差做成一个轻量 contact head，用来**减速、回退、调夹爪合规**，而不是直接当力控。这是低成本、高可解释的增量。

一句话：**第 7 轮把机械臂当“两个 7 维执行器”；本轮把它当“一个有角色、有接触、有冗余的身体”。**

### 1.3 创新点挖掘：不是头脑风暴，是“轴切片矩阵 + 探针 + 成本/收益排序”

本轮第三个词是“创新点挖掘”，它不该产出一张 20 条点子的清单，而该产出一套**可执行的研究流程**：

1. **轴切片矩阵**：32 任务 × 5 轴 = 160 个格子。每个格子记录成功/失败、失败模式、候选杠杆、预估成本。先找“0% 格子”和“80% 格子”（四轴成功、一轴归零），因为它们的边际收益最大（0.2 任务分 = 0.625pp 总分）。
2. **探针套件**：每个候选创新点先做最便宜的证伪实验，而不是先训大模型。视觉编码器用“冻结特征 + 线性 probe 预测容器位姿”证伪；机械臂用“跟踪残差分类接触”证伪；接口用“调试槽 10 分钟”证伪。探针不过，直接砍。
3. **成本/收益排序**：每个格子算 `预期增益 / 工程周`，优先做“高增益、低依赖、可回退”的格子。第 7 轮的 ICR 是反例：证据强、但延迟/缓存/训练耦合重，本轮降为次级。

一句话：**创新点挖掘不是“想做什么”，而是“先证明哪个格子值得做，再决定做多大”。**

## 2. 本轮主判断：先消灭“轴零点”，再抬地板

### 2.1 一个更锋利的失败模型

把失败分成六类，并映射到轴：

| 失败模式 | 典型任务 | 主要轴 | 现有证据 | 候选杠杆 |
|---|---|---|---|---|
| 感知轴零点：背景/位置/干扰物/未见物体导致直接归零 | 全部，尤其 T04/T06/T11/T13/T24/T27 | 位置、背景、干扰物、未见 | Spa-Bench：ID 67.5–73.3% → OOD 40.7–52.0% [S46] | GEO 编码器 + 语义保持 + 可靠性门控 |
| 双臂协调失败：一手挡另一手、辅臂不动、角色固定 | T10/T11/T12/T18/T22/T23/T32 | 位置、未见、人类 | PA-BiCoop +48% / 真机 +50% [S23] | ARM-R 角色 token + 辅臂主角系动作 |
| 接触/插入失败：插头、锁、拉链、注射器、电池 | T05/T10/T12/T19/T23/T26/T31/T32 | 位置、未见、人类 | CoPRE 82.2% / 5.5N [S26]；Blind Dexterity 残差 [S27] | contact head + 减速/回退/合规 |
| 恢复失败：人类干扰后不回退、不重试 | T14/T19/T24/T27 等 | 人类（20%） | 第 7 轮 NRB；官方 human 备注 [S2] | NRB + SSG 状态机 + 可逆信念 |

| 完成验证失败：假完成、掉落、未到位 | T27/T10/T19/T31 | 位置、未见、人类 | 第 7 轮 SSG/SVL | SSG 谓词 + SVL 落点闭环 |

这个失败模型比第 7 轮的“放置闸门”更细：放置仍然是成功闸门，但**轴零点可以在放置之前就把 episode 杀死**。先修感知，再修协调，最后修放置——这是本轮的顺序。

### 2.2 为什么视觉编码器是当前最高杠杆

1. **它同时打四轴**：位置、背景、干扰物、未见物体。没有任何其他单一组件有这种覆盖。
2. **数据免费**：官方双目 + 标定 + URDF，不需要额外采集；6,400 条子集就能预训练。
3. **文献成熟到可以集成**：StereoVLA/ExStereo/StereoPatch 证明双目接入 VLA 可行；DEM/R²-WAM 证明 DINOv3 表征强；MAPS/PAVE 给出“冻结语义 + 轻量适配”的安全路线。我们不是从零发明，而是补“真实标定 + 可靠性 + 腕部蒸馏 + base 系 token”这块空白。
4. **集成风险可控**：GEO 作为 gated adapter 接在 WLA 上，零初始化，最坏情况退回原模型；不需要改动作空间。
5. **证伪便宜**：冻结特征 + 线性 probe，1–2 天就能知道“几何特征是否真的预测容器位姿”。不过就砍，不浪费 4 周。

### 2.3 为什么机械臂是第二杠杆，而不是另一个编码器

- 20+ 任务双手都活跃；固定左右分工在阶段性任务上会错。
- 人类干扰轴占 20%，恢复需要“停—看—退—重试”，这本质上是双臂/身体控制，不是视觉。
- 接触密集任务（插入/拧/拉链/注射）在 32 任务里占比高，且现有 VLA 普遍弱。
- ARM-R 可以作为 WLA 的动作头上加头，风险低于重训视觉塔；与 GEO 互补而非竞争。

## 3. 方案轮廓：GEO-ARM

```text
四路 RGB + 关节/EE/夹爪/腰/腿
        │
        ├─ GEO-Enc（训练时用双目/标定；推理时用 RGB）
        │    ├─ 头部双目 → 深度/点图 → base 系
        │    ├─ 腕部单目 → 跨视角蒸馏 → base 系
        │    ├─ 可靠性门控（透明/反光/细长）
        │    └─ 冻结语义 + 几何 cross-attn → N 个 3D token
        │
        ├─ WLA-1.0-Base（Qwen2.5-VL + DiT-L，54 维动作专家）
        │    └─ gated adapter：3D token → cross-attn context
        │
        ├─ ARM-R 头
        │    ├─ role head（主/辅）
        │    ├─ primary/aux 关节 chunk-delta
        │    ├─ 冗余 token（肘部 swivel）
        │    └─ contact head（q_des − q_t 残差）
        │
        └─ PILOT 接线
             ├─ SSG 成功门控 / 失败诊断
             ├─ PGL/OPT 3D 容器位姿与放置
             ├─ SVL 落点闭环
             └─ NRB 人类干扰恢复

输出：joint chunk (H,7)×2 + gripper (H,1)×2 + pivot (H,7)
```

**推理路径**：4 路 RGB + proprio → GEO-Enc（~80–150ms）→ 3D tokens + reliability → WLA/DiT（~300–600ms）→ ARM-R 头 → 1 秒 chunk。异步：上一 chunk 执行时预计算下一 chunk 的视觉；如果超时，退回上一 chunk 的后半段或零阶保持。

**训练路径**：官方数据 → 双目伪深度/点图 → GEO 自监督预训练（depth + CalibConsist + 语义蒸馏）→ 接 WLA（冻结语义塔，LoRA/适配器）→ ARM-R 头监督 → 轴扰动微调 → 调试槽探针 → 全量。

**单模型审计**：GEO/ARM-R/WLA 是学习组件；SSG/PGL/OPT/SVL/NRB 的查询与规则是确定性代码；检索库是数据不是模型。模型卡逐项披露。

**Fallback**：双目不对齐→单目深度 + 语义；GEO 无增益→关 adapter；joint 跟踪差→EE；pivot 不明→hold；延迟超 1s→降分辨率/跳腕部/预取。

## 1. 事实核对（本轮新增，全部一手；来源表见 §13）

### 1.1 排名规则：成功率优先，步骤分只是 tiebreaker

官方参赛手册（飞书，中英文两版）[S12][S13] 要点（转述，非逐字）：

> 实时榜单按 32 个任务的总平均成功率进行排序；成功率相同时，按总平均步骤分排序；若仍相同，则提交日期较早的模型排序靠前。

> 每个任务评测 10 次，覆盖 5 类泛化场景，每类 2 次；单次评测限时 180 秒。

这条规则是本轮的第一性事实。它意味着：

- **主目标**：32 任务平均成功率 \(S\)。
- **次目标**：仅在 \(S\) 并列时，比较平均步骤分 \(P\)。
- **第三目标**：仅在 \(S,P\) 都并列时，比较提交日期。
- 任何“牺牲成功率换步骤分”的策略都是错的；任何“只提步骤分”的工作默认降级。

第 7 轮的步骤分算术仍然有用，但用途变了：它是**失败诊断**（钱丢在哪一步），不是**目标函数**。SSG 仍然要知道步骤，但它的 KPI 是“成功/失败”，不是“步骤分”。

### 1.2 10 runs = 5 轴 × 2 次；轴切片算术

由“每个任务 10 次、5 类泛化、每类 2 次”推出：

| 泛化轴 | 每任务次数 | 权重 |
|---|---:|---:|
| 位置（position） | 2 | 20% |
| 干扰物（distractor） | 2 | 20% |
| 背景（background） | 2 | 20% |
| 未见物品（unseen object） | 2 | 20% |
| 人类干扰（human） | 2 | 20% |

形式化：任务 \(t\) 的成功率

\[
\bar{s}_t=\frac{1}{10}\sum_{a=1}^{5}\sum_{k=1}^{2} s_{t,a,k},
\qquad
S=\frac{1}{32}\sum_{t=1}^{32}\bar{s}_t.
\]

边际收益（假设其余不变）：

| 改动 | 任务 \(\Delta\) | 总体 \(\Delta\) |
|---|---:|---:|
| 1 个任务 1 个轴 0→100% | +20pp | +0.625pp |
| 1 个轴在 32 任务 0→100% | +20pp/任务 | +20pp |
| 所有轴均匀 +10pp | +10pp/任务 | +10pp |
| 1 个任务全轴 0→100% | +100pp | +3.125pp |
| 8 个任务全轴 0→100% | +100pp/任务 | +25pp |

**结论**：按“单位成本 / 可识别性”排序，优先级是 **整任务零 > 轴零 > 均匀抬升**。一个任务全 0（通常是接口/延迟/技能缺失）是 3.125pp 的洞；一个任务单轴 0 是 0.625pp 的洞；把所有轴从 50% 抬到 60% 只有 10pp 总量，但需要全面进步。先找整任务零，再找轴零。

第 7 轮的“放置是唯一跨轴杠杆”仍然成立：放置失败会在所有轴上杀死成功。但**它不是唯一的结构化机会**；感知轴零点是更大、更可识别的机会。两者不冲突：GEO 修感知轴，SSG/PGL/OPT/SVL 修放置闸门。

**深度误差的量级**（用它来决定“GEO 能做什么、不能做什么”）：

双目深度误差近似

\[
\sigma_Z \approx \frac{Z^2 \sigma_d}{f B}.
\]

取 \(f=282\)px、\(B=0.05825\)m、视差误差 \(\sigma_d=0.5\)px：

| 距离 \(Z\) | 深度误差 \(\sigma_Z\) |
|---:|---:|
| 0.3m | ~2.7mm |
| 0.5m | ~7.6mm |
| 0.8m | ~19.5mm |
| 1.0m | ~30.4mm |

所以：**头部双目在 0.3–0.5m 是厘米级；1m 外是 3cm 级，不能直接做毫米级插孔。** 这决定了 GEO 的定位是“粗到中的 3D 先验”，最后毫米级必须靠腕部近景 + 本体/接触。不要把 GEO 说成“替代力控”；它是“让策略知道东西大概在哪、朝向如何、哪块几何不可靠”。

腕部彩色内参的针孔近似给出约 72° 水平 / 58° 竖直 FOV；腕部实际是广角/强畸变镜头，**以数据内参 + 去畸变为准，不直接用 FOV 做几何。**

## 2. 评分算术：为什么“整任务零/轴零”是第一优先级

### 2.1 形式化

\[
S=\frac{1}{32}\sum_{t=1}^{32}\frac{1}{10}\sum_{a=1}^{5}\sum_{k=1}^{2}s_{t,a,k}.
\]

把每个任务看成 5 个 20% 的切片。任务 \(t\) 的分数是切片平均，不是最好切片，也不是最差切片。一个切片归零，任务上限就是 80%。

### 2.2 边际收益与优先级

| 优先级 | 洞 | 单任务增益 | 总体增益 | 识别方法 |
|---|---|---:|---:|---|
| P0 | 整任务 0%（全 10 次失败） | +100pp | +3.125pp | 调试槽/计分跑/离线成功预测 |
| P1 | 单轴 0%（其余四轴高） | +20pp | +0.625pp | 轴切片矩阵 + 失败分类 |
| P2 | 单轴 50%（其余高） | +10pp | +0.313pp | 同上 |
| P3 | 全轴各 +10pp（如 50%→60%） | +10pp | +10pp 总量 | 全面能力提升 |

P0 的洞最大，但通常是接口/延迟/技能缺失，修复可能很贵；P1 的洞中等，但通常有明确的感知/恢复杠杆，修复便宜。**先用探针找 P0/P1，再按成本排序，不要先做 P3。**

### 2.3 统计功效：每轴只有 2 次，别过度解读

- 320 trials；若 \(p=0.3\)，二项标准误 \(\sqrt{0.3\cdot0.7/320}\approx2.6\)pp。
- 但 trials 按任务/轴聚类，有效样本远小于 320；32 个任务才是独立单位。
- 每个任务每轴只有 2 次，单格估计极噪声；不能因为“某任务某轴 1/2”就断定它强/弱。
- 用分层 Beta(2,2) 平滑：\(\tilde{p}_{t,a}=(k+2)/(n+4)\)；再按任务/轴池化。
- 用任务级配对 bootstrap（10,000 次）比较 A/B；报告 95% CI；CI 跨 0 不上线。
- 目标增益 +5pp 在 32 任务上约 1.4–1.9 SE，属于“需要配对设计才看得见”的量级；不要用单次 320 trials 的原始均值下结论。

### 2.4 任务组合规则

1. **Tier 0（整任务零候选）**：接口/接触风险最高的任务——T10 PlugCharger、T12 Unlock、T19 ZipUp、T26 PlugInEthernet、T31 OrganizePencilCase、T32 SyringeWaterTransfer。若调试槽显示 0%，先修接口/接触，再谈模型。
2. **Tier 1（轴零候选）**：T04 FruitSorting、T06 ColorArrangement、T11 PickOutBatteries、T13 ArrangeTestTubes、T24 ConveyorSorting、T27 StackBowls。这些任务对位置/背景/干扰物/未见物体敏感，GEO 的 probe 优先在这几个任务上做。
3. **Tier 2（双臂/接触）**：T10、T11、T12、T18、T22、T23、T32。ARM-R 的 A/B 优先在这几个任务上做。
4. **Tier 3（长程/恢复）**：T09、T15、T16、T17、T28、T29、T30。NRB/SSG/SVL 的 A/B 优先在这几个任务上做。
5. **Tier 4（其余）**：最后补。

这是**假设分桶**，不是官方难度；真实分桶由 P0/P1 探针和调试槽更新。每个格子的成本/收益记录在 §6.2 的矩阵里。

### 2.5 与第 7 轮步骤分框架的差异

| 维度 | 第 7 轮 | 第 8 轮 |
|---|---|---|
| 主目标 | 步骤分（39.8%/59.7%） | 成功率（10 次平均） |
| 步骤分 | 主分/第二目标 | 仅 tiebreaker + 诊断 |
| 放置 | 唯一跨轴杠杆 | 成功闸门之一；感知轴零点是另一杠杆 |
| 动作空间 | EE | joint chunk-delta（EE 回退） |
| 视觉 | 2D 锚点 + 语义 | 3D 度量 token + 可靠性 |
| 双臂 | 未单独建模 | 动态主辅角色 + 接触 |
| 评测 | TCLB 为主 | 探针 + 调试槽 + 计分跑 |

### 3.2 GEO-Enc：标定感知的度量 3D 编码器

#### 输入

- \(I_h^L, I_h^R\)：头部左右 RGB，480×640。
- \(I_w^L, I_w^R\)：腕部左右 RGB，480×640。
- \(q \in \mathbb{R}^{14}\)：双臂关节；\(g \in \mathbb{R}^2\)：夹爪；\(p_{ee} \in SE(3)^2\)：EE base 位姿；\(q_{waist} \in \mathbb{R}^3\)：腰；\(q_{leg} \in \mathbb{R}^{12}\)：腿。
- 标定：\(K_h^L, K_h^R, R_h, T_h\)（已校正，\(R_h\approx I\)）；\(K_w^L, K_w^R\)；腕部手眼 \(T_{EE\leftarrow C_w}\)（从数据标定）；头部安装 \(T_{B\leftarrow C_h}(q_{waist})\)（URDF + 数据集 `state_d435` 校准）。

#### 头部双目分支

1. 以 240×320 跑快速双目模型（Fast-FS / FoundationStereo-lite）[S40][S41]，得到视差 \(d\) 和置信度 \(c_s\)。
2. 深度 \(Z_h = f_h B / d\)，其中 \(f_h\approx282\)px、\(B=0.05825\)m。
3. 反投影 \(P_h^{C} = Z_h K_h^{-1}[u,v,1]^T\)。
4. 变到 base：\(P_h^{B} = T_{B\leftarrow C_h}(q_{waist})\,P_h^{C}\)。
5. 置信度融合：左右一致性、代价熵、时序一致性；低置信度不直接丢，而是保留 token + 低 reliability，让策略学会忽略。

#### 腕部单目分支

1. 用冻结 DINOv3 特征 + 轻量深度头 \(f_\theta\) 预测腕部相机系点图 \(P_w^{C}\) 和置信度 \(c_w\)。
2. 变到 base：\(P_w^{B} = T_{B\leftarrow EE}(p_{ee})\,T_{EE\leftarrow C_w}\,P_w^{C}\)。
3. 手眼 \(T_{EE\leftarrow C_w}\) 从数据标定（不是硬编码；issue #132 的 sim 外参错位就是反例 [S15]）。
4. 腕部近距离（0.1–0.3m）负责抓取/插入的精细几何；头部双目负责场景/容器/路径的粗几何。

#### 3D token 化

- 把 \(P_h^B \cup P_w^B\) 体素化到 1cm（桌面工作区约 1m³ → 100×100×50 稀疏体素），或 FPS 采样 \(N=1024\) 个点。
- 每个 token：\(x_i = [\text{Fourier}(P_i^B), f_i^{sem}, r_i]\)，其中 \(f_i^{sem}\) 是 DINOv3/SigLIP 在对应像素的特征，\(r_i\) 是 reliability。
- 用交叉注意力把几何 token 与冻结语义 token 融合（StereoPatch 式 patch 对齐 [S18]）：几何提供“在哪/多远”，语义提供“是什么/怎么用”。
- 输出：\(N\) 个 1024 维 token + \(N\) 个 reliability + 可选的全局场景 token。

#### 可靠性门控

\[
r_i=\sigma\big(w_0+w_1 c_s+w_2 c_w+w_3 c_t+w_4 c_p\big),
\]

其中 \(c_s\) 双目置信、\(c_w\) 腕部单目置信、\(c_t\) 时序一致、\(c_p\) 相位先验（抓取/插入/放置）。训练目标不需要人工标签：用 CalibConsist 的重投影误差、跨视角深度差、时序深度差作为自监督信号；高误差 → 低 reliability。透明的药瓶、金属锁、试管、拉链、注射器会让 \(c_s\) 低，策略自动降权并转向语义/本体/接触。

#### 输出接口

- 3D token 投影到 WLA 的 cross-attention 维度（2560），与 Qwen2.5-VL 的语义 token 拼接。
- 额外输出（给 PGL/OPT/SVL）：容器 6D 位姿、抓取点/接近向量、放置点、场景点图。这些是**度量**输出，不是 2D 框。
- 额外输出（给 ARM-R）：腕部点图、EE 附近的 3D 占据、接触候选区域。

#### 最小可行版（W2 探针）

- 只用头部双目 + 冻结 DINOv3 + 线性/MLP depth head；不做腕部蒸馏、不做可靠性。
- 目标：在 32×20 episodes 上，用冻结特征预测容器位姿/放置成功，比较 SigLIP vs DINOv3 vs 双目点图。
- 若双目点图 probe 相对 SigLIP 提升 <20%（相对），GEO 主线降级为“单目语义 + 接触”，不投入 4 周。

### 3.3 CalibConsist：跨视角自监督

给定两个视角 \(i,j\)、已知相对变换 \(T_{ji}\)、预测点图 \(P_i,P_j\)、置信度 \(c_i,c_j\)：

1. 把 \(P_i\) 投到 \(j\)：\(\tilde{x}_j=\pi_j(T_{ji}P_i)\)。
2. 在 \(P_j\) 采样：\(\tilde{P}_j=\text{sample}(P_j,\tilde{x}_j)\)。
3. 掩码：\(m=c_i c_j \cdot \text{visible}(\tilde{x}_j)\cdot(1-\text{occlusion})\)。
4. 损失：

\[
L_{cc}=\sum_{x\in\Omega} m(x)\,\rho\big(\|\tilde{P}_j(x)-T_{ji}P_i(x)\|\big)
+\lambda_r\sum_i\|r_i-\hat{r}_i\|^2.
\]

5. 对头部 L/R，\(T_{ji}\) 是校正后的纯平移；对头-腕，\(T_{ji}\) 来自 EE 位姿 + 手眼；只取重叠区域（腕部看到桌面/物体时）。对时序，用 EE 运动把 \(P_t\) 变到 \(t+1\)，静态场景假设；运动物体用光流/特征匹配掩掉。

**为什么这是新的**：StereoVLA 用合成双目 + 相机参数估计，ExStereo 用双目 mid-training，StereoPatch 用干净深度；它们没有用“真实已标定的头-腕跨视角”做自监督，也没有把腕部单目蒸馏成度量。CalibConsist 把官方标定变成免费监督，且不依赖腕部深度传感器。

### 3.4 GEO-Future：轻量 3D 跟踪世界模型

不生成视频，只预测 3D 点轨迹：

- 从当前 3D token 里采样 \(K=256\) 个查询点（夹爪、物体、容器、接触区域）。
- 用一个小 transformer 预测 \(\tau=1,2,4,8\) 个 chunk 后的 3D 位置 \(\hat{P}_{t+\tau}\)。
- 监督：数据集下一帧的双目点图 / 光流跟踪 / 特征匹配；用循环一致性过滤。
- 损失：

\[
L_{track}=\sum_{\tau}\sum_{k}m_{k,\tau}\big\|\hat{P}_{k,t+\tau}-P_{k,t+\tau}\big\|_1.
\]

- 推理用途：
  1. **碰撞预判**：预测辅臂/物体轨迹，提前减速。
  2. **接触预判**：预测夹爪与物体的距离变化，触发 contact head。
  3. **落点验证**：释放后物体是否停止运动（SVL）。
  4. **双臂协调**：预测辅臂未来位置，避免主臂撞辅臂。
- 证据：JAMB 用 3D point track + 关节动作扩散，sim +23.9pp、real +50pp [S29]；R²-WAM 用未来特征预测 +9.3pp [S20]。我们不生成像素，只预测稀疏 3D 轨迹，成本低得多。
- 最小版：只预测夹爪 + 被操作物体的 16 个点；若离线跟踪误差 >2cm，砍掉。

### 3.5 ARM-R：主辅臂角色 + 关节空间 chunk-delta + 接触残差

#### 角色头

- 输入：WLA hidden state + GEO tokens + language。
- 输出：\(\rho\in\{L,R\}\)（主臂）及辅助臂。
- 弱标签：每帧 EE 速度、夹爪开合、朝目标运动；主臂 = 速度大/夹爪闭合/朝目标；辅臂 = 支撑/静止/开爪。对“双手都动”的相位，用 PA-BiCoop 式角色分配（朝目标推进的一侧为主）。
- 损失：CE + 熵正则（避免角色抖动）；推理时用滑窗投票，角色每 chunk 最多切换一次。

#### 主/辅解码器

- 主臂：\(\Delta q^P_{t:t+H}\in\mathbb{R}^{H\times7}\)，base 系关节 delta。
- 辅臂：以主臂为条件（相对位姿 embedding + 主臂动作），输出 \(\Delta q^A_{t:t+H}\)；**不硬做 IK**，仍是关节 delta，避免 IK 误差。
- 合并：按 \(\rho\) 写回左右臂；累加得到绝对目标：

\[
q^{cmd}_{t+k}=q_t+\sum_{j=1}^{k}\Delta q_{t+j},\quad k=1..H.
\]

- 裁剪到关节限位/速度限位；chunk 内用三次插值平滑。

#### 冗余 token（肘部）

- 从 7 关节算肘部 swivel 角 \(\phi\)（或直接用关节角的 null-space 参数）。
- 预测 \(\phi\) 作为辅助目标；在 joint-space 策略里作为输入 token，帮助策略保持一致的肘部姿态；在 PGL/OPT 需要 IK 时，用 \(\phi\) 选解。
- 受限空间任务（T08 书架、T09 工具箱、T18 背包、T28 收纳盒、T29 盒子）优先验证。

#### 接触头

- 输入：跟踪残差 \(e_t=q^{cmd}_{t-1}-q_t\)（按关节范围归一化、低通）、夹爪命令-状态差、GEO 腕部点图、相位 token。
- 输出：接触概率 \(c_t\) + 类型（自由/接触/阻塞）。
- 标签：夹爪闭合 + 物体运动/EE 停滞的启发式；CoPRE/Blind Dexterity 的残差阈值 [S26][S27]；人工抽检 100 段。
- 用途：
  1. \(c_t\) 高 → 缩小 chunk 幅度（0.5×），降低冲击。
  2. \(c_t\) 高 + 进度停滞 → 回退 1–2cm 再重试。
  3. 插入类任务 → 用残差做“软着陆”信号，而不是硬力控。
- 停止条件：接触 AUC <0.7 → 只用夹爪开度/视觉，不用残差。

#### 动作参数化

- 内部：chunk-delta \(\Delta q\)；输出：绝对关节目标 \(q^{cmd}\)。
- 证据：delta 优于 absolute；同体、数据足时 joint 优于 task-space [S28]；主动作字段是关节 [S4]。
- 回退：调试槽若 joint 跟踪误差 >2° 或成功率低于 EE，切 EE（EE 动作头仍保留）。

#### Pivot 门

- 默认：hold 上一条 pivot（零 delta）。
- 调试槽确认 pivot 控制腰/底盘且有用后，开一个小 gate（初始化 0）学习 delta；否则永远 hold。
- 腰部运动较大的任务（OrganizeTools 0.183、StorePaddle 0.102、FoldTowel 0.090、OrganizeStationery 0.069、PourOutMedicine 0.063、PlugCharger 0.059）优先验证 [S2]。

### 3.6 与 WLA / DEM / UnifoLM-VLA-0 的接口

WLA-1.0-Base 配置 [S34][S37]：

- Qwen2.5-VL backbone + DiT-L action model。
- `action_dim=54`、`action_horizon=30`、16 layers、hidden 1024、cross-attention dim 2560、state projector input 120。
- Apache-2.0、12.47GB、lastModified 2026-09-28。

接法：

1. GEO token 1024 → MLP → 2560，拼到 DiT 的 cross-attention context（或加一个独立的 cross-attn block）。
2. 零初始化 gate \(\alpha\)：\(\text{ctx}=\text{ctx}_{vlm}+\alpha\cdot\text{ctx}_{geo}\)；训练开始等价于原 WLA。
3. 动作头切片：WLA 输出 54 维 → UniBot joint 23 维（7+7+1+1+7）或 EE 21 维；其余维度忽略。先在 UniBot 数据上重训动作头，再解冻 LoRA。
4. 冻结语义塔，只训 Geo-Adapter + 动作头 + LoRA（rank 64）；防止 PAVE 式 affordance 退化 [S22]。
5. 备选底座：
   - **DEM 风格**：DINOv3 ConvNeXt-B + NeoBERT + MeanFlow；适合低延迟/小算力，但需要自己接动作头 [S19]。
   - **UnifoLM-VLA-0**：Qwen2.5-VL-7B、340h 真机、12 类 G1 任务、离散动作 + chunking + 前向/逆向动力学 [S35]；3D 检测/空间 CPT 可能对 GEO 更友好。
6. Bake-off 标准：离线动作误差、调试槽单任务成功率、1 秒 chunk 延迟。WLA 先跑（集成风险最低）；DEM 作延迟回退；UnifoLM-VLA-0 作第二候选。

### 3.7 与 PILOT 组件的接线

- **SSG**：保留步骤图/谓词头，但只用于成功门控、假完成检测、失败诊断；不再用步骤分加权训练。步骤分只在 tiebreaker 时优化（例如“尽量多做一步”作为次级奖励）。
- **PGL**：2D 锚点升级为 3D 锚点：GEO 给容器/槽位的 3D 位姿，渲染/投影只用于可视化与调试；策略直接吃 3D token。
- **OPT**：用 GEO 的容器 6D 位姿 + 演示释放位姿统计；K 条检索仍在，但输入从 2D 检测换成 3D 位姿；透明/小件失败时回退到 ICR 相位先验。
- **ICR**：降为次级；只做相位/位姿先验，缓存编码，延迟预算内开；不作为主回路。
- **SVL**：用 GEO-Future 预测落点轨迹 + 释放后稳定性检测；目标从“加分”改为“把失败转成功”；预算守卫（180s）。
- **NRB**：人类干扰轴 20%，升级为一等组件；官方备注回放 + 通用扰动兜底；与 SSG 的可逆信念联动。
- **DebugLoop/CalibProbe**：调试槽只回答接口/标定/动作空间问题；每个大版本最多 1 槽；记录表见 §6.3。

## 4. 数据引擎

### 4.1 数据清单与子集

| 用途 | 数据 | 规模 | 备注 |
|---|---|---|---|
| GEO 预训练 | 32 任务 × 200 episodes | 6,400 条 | 覆盖透明/反光/细长/布料/盒子 |
| 策略训练 | 32 任务全量 | ~33k | 按任务均衡采样 |
| 探针 P0 | 32 任务 × 20 episodes | 640 条 | 抓取/放置/插入帧 |
| 标定验证 | 每任务 5 条 | 160 条 | 双目极线/腕部手眼 |
| 轴扰动 | 8 任务 × 50 条 | 400 条 | 背景/位置/干扰物/未见 |
| 人类干扰 | 官方备注 32 任务 | 64 条（2/任务） | 回放/合成 |

### 4.2 标定与 3D 伪标签

1. 读 `camera_params`（head_stereo、wrist color/IR）[S4]。
2. 头部双目：用 `rectified=true` 直接算视差；`Z=fB/d`；反投影；用 `state_d435`/`state_torso` + URDF 校准头部安装（不是硬编码）。
3. 腕部：用 `p_ee` + 手眼 \(T_{EE\leftarrow C_w}\) 变到 base；手眼从数据标定（标定板/已知物体/优化重投影）。
4. 生成点图/法向/深度置信；按左右一致性、时序一致性、EE 有效性（`recomputed_ee_valid`）过滤。
5. 每个 episode 存：`P_h^B`、`P_w^B`、`c_s`、`c_w`、`K`、`T`、`q`、`p_ee`、`g`、`q_waist`、语言、阶段标签。

### 4.3 跨视角对构建

- 头部 L/R：所有帧；校正后纯平移，最容易。
- 头-腕：只在腕部视野与头部视野重叠时（伸手、抓取、放置、插入）；用特征匹配 + 深度一致性筛选；重叠 <15% 的帧丢弃。
- 时序：相邻帧；用 EE 运动补偿；运动物体用光流掩码。
- 每对存：\(T_{ji}\)、重叠 mask、置信度、有效像素比例。

### 4.4 主辅角色/接触标签

- 角色弱标签：
  - 主臂分数 = EE 速度 + 夹爪闭合 + 朝目标位移 + 接触概率；
  - 辅臂 = 另一侧；若两侧分数接近，标“双主”并加熵正则。
  - 用 100 段人工抽检校准阈值。
- 接触弱标签：
  - \(e_t=q^{cmd}_{t-1}-q_t\) 的范数超过任务特定阈值；
  - 夹爪闭合 + EE 停滞/物体运动；
  - 插入/拧/拉链/注射器阶段人工标注正样本。
- 冗余标签：从关节角算肘部 swivel \(\phi\)；作为辅助回归目标。

### 4.5 轴扰动数据（诊断/微调，不是主训练）

- **背景**：分割桌面/背景，替换为其他 episode 的背景；保持光照/阴影大致合理。
- **位置**：平移物体 mask 3–15cm；保持接触关系。
- **干扰物**：叠加其他任务的物体；不遮挡目标关键部位。
- **未见物体**：留出物体实例/颜色/形状；用 3D 资产替换（许可逐个核）。
- **人类干扰**：按官方 `human_1_note`/`human_4_note` 回放 1-DOF 平移/撤销 [S2]。
- **用途**：探针/诊断/低比例微调；不作为主训练，避免合成负迁移。

### 4.6 质量过滤

- 双目：左右一致性误差 >1px 的像素降权；视差 <0 或 >max 的丢弃。
- 腕部：深度头置信度低 / 重投影误差 >2px 的帧降权。
- EE：`recomputed_ee_valid=0` 的帧不用于手眼/位姿监督。
- 动作：关节速度/加速度超限的帧标记；不直接丢，降权。
- 语言：5 条复述全保留；训练时随机采样一条 [S5]。

## 5. 训练配方

### 5.1 阶段

| 阶段 | 内容 | 数据 | 时间 | 输出 |
|---|---|---|---|---|
| Stage 0 | 冻结特征 probe | 640 条 | 1–2 天 | 视觉路线 go/no-go |
| Stage 1 | GEO 预训练（depth + CalibConsist + 语义蒸馏 + reliability） | 6,400 条 | 3–5 天（8×H100） | GEO-Enc |
| Stage 2 | WLA + Geo-Adapter（冻结 VLM，LoRA/Adapter） | ~33k | 5–7 天 | 策略底座 |
| Stage 3 | ARM-R 头（role/contact/redundancy） | ~33k | 2–3 天 | 完整策略 |
| Stage 4 | 轴扰动微调 + 难任务 | 400 + 难任务 | 2–3 天 | 鲁棒版 |
| Stage 5 | 调试槽 + 计分跑 | 1 任务/全量 | 1–2 周 | 最终提交 |

### 5.2 损失

\[
L=L_{act}+\lambda_1 L_{depth}+\lambda_2 L_{cc}+\lambda_3 L_{sem}
+\lambda_4 L_{role}+\lambda_5 L_{contact}+\lambda_6 L_{track}+\lambda_7 L_{red}.
\]

- \(L_{act}\)：动作 chunk 的 L1/Huber（关节 delta + 夹爪 + pivot）。
- \(L_{depth}\)：头部双目深度/点图 + 腕部蒸馏。
- \(L_{cc}\)：CalibConsist。
- \(L_{sem}\)：冻结 DINOv3/SigLIP 特征蒸馏（防语义漂移）。
- \(L_{role}\)：角色 CE + 熵。
- \(L_{contact}\)：接触 BCE（弱标签）。
- \(L_{track}\)：GEO-Future 轨迹。
- \(L_{red}\)：肘部 swivel 回归。

建议权重：\(\lambda_1=0.5\)、\(\lambda_2=0.2\)、\(\lambda_3=0.1\)、\(\lambda_4=0.1\)、\(\lambda_5=0.1\)、\(\lambda_6=0.1\)、\(\lambda_7=0.05\)；先冻结 \(\lambda_2,\lambda_6\) 做最小版，再逐步加。

### 5.3 超参

- 动作 chunk \(H=30\)（1 秒 @30Hz）；训练时随机取 chunk 起点。
- LoRA rank 64；Geo-Adapter hidden 2560；dropout 0.1。
- 视觉输入 480×640；双目视差 240×320；腕部 320×240（去畸变后）。
- Batch 64–128；LR：Adapter 1e-4、LoRA 1e-5、动作头 3e-4；cosine。
- 语言：5 条复述随机采样；10% 丢语言（学视觉）。
- 图像增强：JPEG q90–95、亮度/对比度、轻微模糊；模拟传输压缩。
- 训练时随机丢弃一路相机（防单路过拟合）；推理时四路全开。

### 5.4 算力与时间

- 训练：8×H100 80GB；Stage 1 3–5 天、Stage 2 5–7 天、Stage 3 2–3 天、Stage 4 2–3 天；总计 3–4 周计算。
- 推理：1×H100 或 1×A100；目标 <900ms/chunk（含 4 路解码 + GEO + WLA）；超时降级。
- 数据存储：33k episodes 全量约 811GB；GEO 子集约 50GB；点图缓存约 100GB（可压缩）。

### 5.5 课程

1. 单臂/简单任务（T01/T02/T03/T04/T06/T07/T20/T21/T25/T27）→ 建立动作/视觉基础。
2. 双臂非接触（T11/T13/T15/T17/T22/T24）→ 学角色/协调。
3. 接触/插入（T05/T10/T12/T19/T23/T26/T31/T32）→ 学接触残差。
4. 长程/恢复（T09/T16/T18/T28/T29/T30）→ 学 SSG/NRB/SVL。
5. 轴扰动（背景/位置/干扰物/未见/人类）→ 学鲁棒性。

## 6. 评测协议

### 6.1 三级评测

**P0 细节**（最重要的证伪）：

- 取抓取前/放置前/插入前帧；用冻结特征 + 线性/MLP probe 预测：
  - 容器/目标 6D 位姿（从演示的 EE/物体位姿构造标签）；
  - 放置成功（是否在容差内）；
  - 抓取点热图。
- 比较：SigLIP、DINOv3、头部双目点图、腕部单目点图、融合。
- 若融合相对 SigLIP 提升 <20%（相对），GEO 主线降级；若 >20%，进入 Stage 1。
- 这是“先证伪再投入”的核心。

### 6.4 统计

- 每个任务每轴 2 次 → 用 Beta(2,2) 平滑；报告平滑后均值 + 原始计数。
- 任务级配对 bootstrap（10,000 次）；报告 95% CI。
- 轴级/任务族级分层报告；不要只报总体平均。
- 显著性：CI 跨 0 → 不上线；CI 下限 >0 且效应 >3pp → 进入下一轮。
- 多重比较：32 任务 × 5 轴，做 FDR 校正；探针阶段只看预注册的 8 个任务。

### 6.5 Go/No-Go

| 节点 | 条件 | 不过怎么办 |
|---|---|---|
| W2 P0/P1 | 几何 probe +20%；双目极线 <1px；joint 跟踪 <2° | 关双目/改单目+接触；joint 改 EE |
| W4 GEO adapter | 配对 8 任务 +3pp | 关 adapter；转 ARM-R+NRB |
| W6 ARM-R | 双臂/接触子集 +2pp | 固定角色；去 contact |
| W7 计分跑 | 总体 +5pp（配对 CI 下限 >0） | 回退上一版；只提交稳定版 |
| W8 最终 | 无回归、延迟 <1s、审计通过 | 冻结保守版 |

## 8. 创新点清单（持续迭代）

> 状态：押注=本轮主线；保留=沿用；升级=旧点改造；降级=保留但非主回路；实验=先探针；砍=不做。

### I1 GEO-Enc 标定感知 3D 视觉编码器（新增，押注）
- 动机：官方双目 + 标定是免费度量监督；语义编码器缺几何，放置/插入/堆叠都吃亏。
- 差异：真实已校正双目 + 腕部单目蒸馏 + base 系 token + 冻结语义双路；不是“换 DINOv3”。
- 可行性：数据字段齐；Fast-FS/FoundationStereo/DINOv3 可用；6,400 条子集。
- 资源：8×H100 3–5 天；1 人。
- 步骤：P0 probe → 头部双目 depth → wrist lifting → token 化 → 接 WLA。
- 风险：双目在透明/反光失败；API 标定不一致；负迁移。
- 停止：P0 相对提升 <20% 或 W4 配对 <+3pp。

### I2 CalibConsist 跨视角自监督（新增，押注）
- 动机：头-腕跨视角 + 双目 L/R 是免费监督；不需要腕部深度。
- 差异：用真实标定做自监督，而不是合成双目/估计相机参数。
- 可行性：标定 + EE 位姿 + 特征匹配；只取重叠区。
- 资源：Stage 1 内完成；无额外数据。
- 步骤：L/R 对 → 头-腕对 → 时序对 → 掩码/损失。
- 风险：重叠少/运动物体/手眼误差。
- 停止：腕部点图误差 >1.5cm 或无语义增益。

### I3 腕部单目度量提升（新增，押注）
- 动机：API 只发 RGB；腕部近景是精细操作的关键。
- 差异：用头部双目做教师，蒸馏腕部单目深度；不是买深度相机。
- 可行性：DINOv3 + depth head；头-腕重叠区。
- 资源：Stage 1 内；腕部标定 1–2 天。
- 步骤：手眼标定 → 深度头 → 跨视角蒸馏 → 置信度。
- 风险：手眼错位（issue #132）[S15]；广角畸变。
- 停止：重投影 >2px 或点图 >1.5cm。

### I4 可靠性门控（新增，押注）
- 动机：透明/反光/细长物体双目失败；盲信双目会主动犯错。
- 差异：每 token 的 reliability + 语义/本体/接触回退；现有双目 VLA 没做。
- 可行性：自监督信号（重投影/时序/跨视角）；无需人工标签。
- 资源：Stage 1 内；小 MLP。
- 步骤：置信特征 → reliability 头 → 门控 → 消融。
- 风险：门控过度/不足；透明区仍被用。
- 停止：可靠性 AUC <0.7 或透明任务无增益。

### I5 GEO-Future 3D 点轨迹（新增，实验）
- 动机：轻量世界模型；碰撞/接触/落点预测；JAMB/R²-WAM 证据。
- 差异：稀疏 3D 轨迹，不生成视频；与 ARM-R 接触头联动。
- 可行性：双目点图/光流监督；小 transformer。
- 资源：Stage 1/3 内；1 人周。
- 步骤：采样点 → 轨迹头 → 监督 → 推理接 SVL/ARM-R。
- 风险：跟踪误差/运动物体；增益不稳。
- 停止：轨迹误差 >2cm 或无增益。

### I6 ARM-R 动态主辅角色（新增，押注）
- 动机：20+ 任务双手活跃；固定左右在多阶段任务上会错。
- 差异：role token + 辅臂主角系条件；PA-BiCoop/BiRoAD 证据。
- 可行性：弱标签可从 EE 速度/夹爪/目标方向得到。
- 资源：Stage 3 2–3 天；小头。
- 步骤：角色标签 → 角色头 → 主/辅解码 → 消融。
- 风险：角色抖动/标注噪声。
- 停止：角色准确率 <80% 或子集无增益。

### I7 Joint chunk-delta + 冗余 token（新增，押注）
- 动机：同体、数据足时 joint/delta 优；7-DOF 冗余在受限空间重要。
- 差异：内部 delta、输出绝对关节；肘部 swivel token；不是 EE-only。
- 可行性：数据集动作是关节；API 支持 joint。
- 资源：Stage 2/3；无额外数据。
- 步骤：动作头改 joint → delta 累积 → 冗余头 → 受限任务验证。
- 风险：joint 跟踪差/限位；chunk 累积漂移。
- 停止：跟踪误差 >2° 或成功率低于 EE。

### I8 跟踪残差接触头（新增，保留）
- 动机：API 无力和力矩；插入/拧/拉链需要接触信号。
- 差异：用 \(q^{cmd}-q\) 残差 + 夹爪 + 视觉；不加法传感器。
- 可行性：命令/状态都有；CoPRE/Blind Dexterity 证据。
- 资源：Stage 3 1 天；小 MLP。
- 步骤：残差特征 → 弱标签 → 接触头 → 减速/回退。
- 风险：残差噪声/阈值任务相关。
- 停止：接触 AUC <0.7。

### I9 轴切片矩阵 + 成本/收益组合（新增，押注/流程）

|---|---|---|---|---|
| 排名规则/手册更新 | 低 | 高 | 以官方手册原文为准；每轮复核 | 规则变化 → 重算目标 |
| API 双目与数据标定不一致 | 中 | 高 | CalibProbe 极线/视差；单目回退 | 极线 >1px 且无法校正 → 关双目 |

| 透明/反光双目失效 | 高 | 中 | reliability 门控 + 语义/本体回退 | 低可靠区仍被用 → 强制门控 |
| JPEG/AV1 域差 | 高 | 中 | 训练加 q90–95/AV1 增强 | 离线掉点 >2pp → 加增强 |

## 10. 修订版 8 周计划

| 周 | 目标 | 交付 | Go/No-Go |
|---|---|---|---|
| W1 | 数据/标定/探针 P0 | 6,400 条 manifest；双目/腕部点图；SigLIP/DINOv3/点图 probe；P2 角色/接触标签 | P0 相对 +20% |
| W2 | GEO 最小版 + 调试槽 #1 | 头部双目 depth + 冻结 DINOv3 + 接 WLA；预约调试槽（T27/T10） | 极线 <1px；joint 跟踪 <2°；probe 通过 |

| W4 | WLA + Geo-Adapter | Stage 2 训练；离线动作/成功率；调试槽 #2 | 配对 8 任务 +3pp |
| W5 | ARM-R 角色 + joint chunk-delta | Stage 3 训练；双臂/接触子集 | 角色 >80%；子集 +2pp |
| W6 | 接触 + 冗余 + PILOT 接线 | contact head、GEO-Future、SSG/PGL/OPT/SVL/NRB | 接触 AUC >0.7；无回归 |
| W7 | 轴扰动 + 计分跑 #1 | Stage 4；全量提交；轴切片矩阵 | 总体 +5pp（CI 下限 >0） |
| W8 | 修复 + 最终提交 | 失败分类修复；模型卡；冻结 | 无回归；延迟 <1s；审计通过 |

**里程碑**：M1（W2）P0/P1 通过；M2（W4）GEO +3pp；M3（W5/W6）ARM-R +2pp；M4（W7）计分跑 +5pp；M5（W8）冻结。

**范围阶梯（防止 8 周摊薄）**：

- **MVS（必须）**：WLA + joint chunk-delta + SSG 成功门控 + NRB 官方备注 + GEO 最小版（仅当 P0 通过）。
- **Target（争取）**：MVS + ARM-R 角色/接触 + PGL/OPT 3D 放置 + SVL。
- **Stretch（可选）**：GEO-Future、WLA/DEM/UnifoLM bake-off、L2L、轴扰动大规模。
- **落后时的砍法**：先砍 Stretch，再砍 Target 的非接触部分；MVS 不动。W2 探针不过 → 直接走“ARM-R + NRB + SSG”路线，GEO 只保留单目语义旁路。

## 12. 开放问题

1. API 的 `cam_left_high/right_high` 是否就是数据集那对已校正双目？裁剪/缩放/JPEG 是否改变内参？
2. `action.pivot` 7 维到底控制什么？底盘/腰/高度？是否与 `base_command`/`waist_action_joint` 一一对应？
3. evaluator 是每 chunk 调一次 `get_action`，还是每步调一次只执行第一帧？
4. 官方 5 类泛化的准确名称/顺序？每类 2 次是否固定顺序？人类干扰是否按 `human_1/human_4` 备注采样？
5. 外部数据（自采/实验室/额外 Dex1 数据集）是否允许？预训练权重（含论文方法）是否允许？
6. 单模型边界：确定性代码（SSG/PGL/SVL）、检索库、GEO 的立体匹配是否需在模型卡披露？
7. 腕部真实外参/手眼是否与数据一致？issue #132 的 sim 错位是否也影响真机？
8. 透明/反光物体的真实双目失败率？是否需要偏振/结构光？API 不允许加传感器。
9. 真机评测的机器人数量/并发/延迟上限？1 秒 chunk 是否稳定？
10. 180s 内允许几次重试/自我中断？是否有隐藏规则？
11. 任务成功判定是自动还是人工？容差多大（放置/插入）？
12. 真实榜单何时发布？发布后重跑轴切片矩阵。
