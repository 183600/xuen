## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（双足机器人 → 这不是「固定底座 + 两条手臂」，而是「会晃、会失衡、带 pivot 通道的全身」）**
直觉：表面是桌面操作，但接口里 `action.pivot[7]` 是 joint/ee 都必须返回的共享通道，观测里有 `lower_body[15]`，官方 54 维动作里 base/腰/躯干/双腿全在（F20/F21）。也就是说：即使任务只在桌面上，策略每一步都在下达下身/姿态指令，G1 是全身控制器，不是固定机械臂。
更深的类比：**双足 = 两个时间尺度耦合的控制环**。走路是高频平衡反射（数百 Hz）压在低频导航（几 Hz）之下；操作同样是高频接触/安全反射压在低频语义规划之下。第 2 轮把一切压在「一个 6B VLA 出 chunk」上，等于让「慢脑」承担「快腿」的职责。
反直觉点：**`action.pivot` 是一个「语义空白」通道**——官方 Dex1 action expert 的 slot 表很可能不含 base/pivot（F22），提交接口却强制要求它。谁先搞清 pivot 到底控制什么、底座是否固定、安全 pivot 策略是什么，谁就先拿到一个别人当零向量扔掉的免费自由度/安全分。
还有一层：头部相机的自运动（身体/手臂晃动）是第 6 条「物理泛化轴」，不在官方 5 轴里，却与 5 轴共变。

**灵感 2（边缘计算 → 赛方明确「不提供算力」，算力是选手的问题；延迟稳定性本身就是可信度指标）**
直觉：手册白纸黑字「平台仅进行远程接口调用，不提供模型运行机器」；提交要暴露 N 个端口、N 台机器人并发；交互时延及其波动会被记录、可能随成绩展示（F23/F24）。所以 serving 不是「部署细节」，而是一条被看见的评分/可信度轴。
关键量化：评测按 chunk 执行——`get_action` 返回 T_a 步，评测端执行完再调用下一次。于是 **chunk 长度就是延迟预算**：deadline ≈ T_a·dt，而不是 1 步 dt。这修正了第 2 轮「66ms 单步预算」的默认假设；6B 模型不必每 33ms 跑一次，但必须「每 T_a 步稳定地跑一次」。
更深的分工：边缘计算的正解不是「把 6B 量化塞进边缘」，而是**按时间尺度切分**——语义（做什么/在哪做）低频、大算力、放 GPU 后端；安全/接触/人干预高频、小算力、放服务前端（快腿）。慢脑出参考轨迹，快腿在参考轨迹上做投影与反射。这正是「双足」的工程对应物：两条腿，两种频率。
反直觉点：**N 端口共享后端的 p99 不是平均值问题，而是尾延迟问题**；「来一个算一个」在并发下 p99 爆炸，恰好撞在可信度指标上。要的是 deadline-aware 调度 + 弹性 chunk，而不是更快的单次推理。

**两者统一（本轮）**：双足回答「哪些控制必须快、必须本地」（平衡/接触/安全），边缘回答「快慢两套计算放在哪、怎么在 N 端口并发下稳住尾延迟」，数据引擎回答「快腿和 pivot 的行为从哪学」。第 2 轮赢在数据分布，第 3 轮赢在时间尺度与算力放置：**6B 慢脑决定上限，边缘快腿决定下限（不摔、不抖、不超时）。**

## 2. 严谨定义（先直觉、后定义）

### 定义 1（双时间尺度策略，Two-timescale policy）
直觉：让「慢脑」只负责出参考轨迹，「快腿」负责在参考轨迹上做安全与反射，二者频率不同、职责不混。
严谨：设控制周期为 Δt，chunk 长度为 H，执行相位为 φ∈{0,…,H−1}。慢策略 π_s: 观测历史 → 参考 chunk A_{t:t+H−1}；快控制器 π_f: (s_t, A, φ) → a_t。组合 a_t = π_f(s_t, A, φ)。约束：
- **不重规划语义**：无安全约束激活时，‖π_f(s_t,A,φ) − A_φ‖ ≤ ε；
- **有约束时最小修正**：若约束集 C（关节/速度/稳定性/人干预）激活，a_t = Proj_{A_safe(C)}(A_φ)，即最小偏离参考；
- **频率分离**：π_f 频率 ≥ 1/Δt，π_s 频率 ≤ 1/(H·Δt)。
这样 π_f 是投影/混合算子，不是第二个任务策略——这是「单模型」合规的关键（见风险）。

### 定义 2（chunk 即延迟预算，Chunk-as-budget）
直觉：一次推理要覆盖接下来 H 步，所以只要「推理 + 网络往返」在 H·Δt 内完成，就不会让机器人停顿；H 是拿反应速度换延迟容忍度的旋钮。
严谨：设慢模型 p99 延迟 L、网络 RTT 为 R。
- **同步模式**：deadline D = H·Δt，开环反应时间 R_react = H·Δt。可行条件 L + R ≤ H·Δt，最小 H* = ⌈(L+R)/Δt⌉。H 越大越不怕卡顿、但开环误差与反应时间越大；H 越小反应越快、但越容易停顿。
- **异步模式**：π_f 从缓存 chunk 立即返回 a_t，π_s 在后台刷新；缓存深度需 ≥ ⌈(L+R)/Δt⌉ + 1，chunk 用尽时回退到「上一个安全动作」。此时反应时间与 L 解耦。
- **自适应**：H(t+1) = clip(H(t) + η·sign(L_p99(t) − L*), H_min, H_max)（AIMD 式），按任务阶段（接近段可长、接触/人干预段必须短）切换。

### 定义 3（稳定性包络与 pivot 安全投影，Stability envelope）
直觉：手臂伸得越远，重心越容易出支撑面；pivot 是唯一能补偿的通道，但不能让它乱动。
严谨：设 g^B_t 为体坐标系重力方向（状态[41:44]），由 lower_body 与臂动作估计重心 p_com(a)，支撑多边形为 S。稳定性裕度 m(s,a) = dist(proj_S(p_com(a)), ∂S)。安全集 A_safe(s) = {a : m(s,a) ≥ m_min, 关节/速度界}。快腿做 a* = argmin_{a∈A_safe} ‖a − A_φ‖。若底座在评测中固定，则 pivot 取「保持」，δ=0；若自由，则学习小残差 δpivot = r_θ(arm_action, lower_body)，并约束 ‖δpivot‖ ≤ ρ，只补偿、不改写。

### 定义 4（自运动混淆与本体条件化，Ego-motion confounder）
直觉：相机装在会晃的头上，画面里的「物体在动」可能只是「机器人在动」；这是第 6 条物理泛化轴。
严谨：观测 I_t = W(ξ_t) ∘ I_world + n，ξ_t 为身体/手臂诱导的相机位姿。策略建模 π(a | I_t, ξ_t)，ξ_t 由 lower_body/base 惯性（重力方向 + 角速度）与本体估计。训练时从 32k eps 实测的 p(ξ | 任务阶段) 采样 ξ 并对图像做 warp，目标是让策略对 ξ 不变，而不是把 ξ 当物体运动。

## 4. 设计原则（新增 PR6/PR7，PR1–PR5 保留）

- **PR6 时间尺度分离律**：任何频率高于 1/(H·Δt) 的要求（平衡、接触、安全、人干预），都不得压给高容量语义模型；必须由快腿或确定性控制器承担。与 PR1 互补：PR1 管「做不做」，PR6 管「谁来快做」。
- **PR7 延迟预算律**：每个模块必须声明延迟预算；chunk 长度是预算货币；p99 时延稳定性与动作健康度是一等指标，不是事后补丁。
- PR1–PR5 保留（第 1–2 轮）。

## 0. 本轮新增/升级一览（先过三道闸）

## 1. 创新点详述

### I10 pivot/全身稳定性补全 ★★★★（新）

- **动机**：提交接口强制 `action.pivot[7]`（joint/ee 都必须返回，F21），观测含 `lower_body[15]`；官方 54 维动作空间含 base/腰/躯干/双腿（F20）。但官方 Dex1 action expert 的 slot 表不含 base_pose（WBT 专属，F22），参考策略直接输出零 pivot。于是出现一个「接口强制、模型不产、文档不述」的语义空白。
- **直觉**：桌面任务也需要「站得住、够得着」。手臂前伸时重心前移，pivot/腰/躯干是唯一补偿通道；把它恒零，等于放弃一个免费自由度，甚至可能在长距离伸展时降低稳定性。反过来，乱动 pivot 会引入新的失稳源，所以正确姿势是「最小安全投影」而非「自由学习」。
- **与现有方案差异**：多数队伍把 pivot 当常量零；本点先确认语义，再做「保持 vs 安全投影」的受控选择，并用数据学一个小残差（仅当底座自由时）。
- **技术可行性**：中。核心不确定性是物理语义（Q9），不是算法；一旦确认底座固定，退化为「pivot 保持 + 关节/速度限幅」的确定性安全项，成本极低。
- **所需资源**：0 额外 GPU；1 人周（含向组委会确认、离线回放分析）。
- **落地步骤**：①书面确认 pivot[7]/lower_body[15] 的精确映射、底座固定与否、是否计分；②从 32k eps 统计 pivot/lower_body 的分布与「臂伸展—重心」相关性；③实现三种策略（零/保持/安全投影）离线回放；④L0 用稳定性裕度违规率 + 动作偏离度筛选；⑤真机单任务抽测（仅当底座自由）。
- **风险/合规**：若 pivot 语义被误解，安全投影可能反而干扰任务（缓解：默认「保持」，投影只在裕度低于阈值时激活，且限幅）；底座固定时整项降级为安全限幅，不阻塞主链。

### I11 双时间尺度快腿/慢脑 ★★★★★（新，umbrella）

- **动机**：6B VLA（F26）推理重、频率低；而平衡/接触/人干预/安全需要高频。第 2 轮把两者都压在同一个模型上，违背时间尺度分离。官方又明确「自部署、N 端口并发、时延稳定性被记录」（F23/F24）。
- **直觉（双足的字面工程化）**：双足走路是「快平衡反射 + 慢导航」两层；操作同样应是「快腿（投影/反射）+ 慢脑（语义/轨迹）」。慢脑只决定「去哪」，快腿决定「这一步怎么安全地走」。
- **架构**：
  1. **前端（快腿，CPU，每步 <1ms）**：接收 obs，立即从缓存 chunk 取参考动作 A_φ；做混合/外推、关节与速度限幅、稳定性投影（I10）、人干预检测（I4）、接触状态反射（I3）、离群动作健康检查；chunk 用尽则 hold-last-safe。**不学习任务语义**。
  2. **后端（慢脑，GPU，6B VLA）**：异步生成新 chunk，按 deadline 调度；结果写回每端口缓存；允许用最新 obs 刷新。
  3. **协议**：`PolicyService.get_action` 在前端立即返回，不阻塞后端；每端口独立状态/KV/历史（F23 状态隔离）。
- **关键设计选择**：H>1 时评测端执行整 chunk，快腿只能在 chunk 内预投影（无新观测）；H=1 时快腿是真反射，但需要异步慢脑 + 缓存深度来隐藏延迟。二者的最优切换由 I12 的调度器决定。
- **与现有方案差异**：第 2 轮 I3/I4/I6 是三个独立模块；本点把它们统一为「一个慢脑 + 一条快腿」的时间尺度架构，并明确「快腿不是第二个任务模型」的合规边界。
- **技术可行性**：高。快腿全是确定性算子；异步缓存是标准 serving 工程。
- **所需资源**：1 名 systems 工程师 2 人周；前端 1 CPU 节点；GPU 不变。
- **落地步骤**：①确定性快腿原型（限幅/投影/混合/hold）；②异步缓存与超时回退；③run_client + 模拟并发压测；④消融：快腿 off/on、H 扫描、同步/异步；⑤真机 top-2 确认。
- **风险/合规**：**最大风险**是「快腿被判定为第二个模型」——缓解：v1 只用确定性投影（无学习任务策略）；v2 若需学习，只做「与主干同权重的小头」并保持单次前向；向组委会书面确认「低层安全控制器」是否属于允许组件。另：H>1 时快腿无新观测，反射能力有限（缓解：接触/人干预段切 H=1）。

### I12 尾延迟感知 N 端口调度 + 弹性 chunk ★★★★（新）

- **动机**：N 台机器人、N 个端口、共享后端（方式二，F23）；交互时延及其波动被记录、可能展示（F24）。naive「来一个算一个」在并发下 p99 爆炸，恰好撞可信度指标。
- **直觉**：不是「把单次推理做快」，而是「让最慢的那 1% 调用不变慢」。chunk 长度是可调预算：负载高时增大 H（少调用、降争用），负载低或接触段时减小 H（提反应）。
- **与现有方案差异**：I6 v2 关注单端口确定性；本点关注多端口并发的尾延迟、状态隔离与降级。
- **技术可行性**：高（标准调度 + 每端口隔离）。
- **所需资源**：调度器 1 人周；并发压测脚本 3 天；无需额外 GPU。
- **落地步骤**：①每端口独立队列/状态/KV；②deadline-aware 批处理（等待窗口 = min(批窗口, 最紧 deadline−now)）；③AIMD 弹性 H；④超时降级到快腿 hold-last-safe；⑤动作健康监控（马氏距离/速度限幅/平滑）；⑥模拟泊松到达测 p99/方差/stall。
- **风险**：自适应 H 可能让时延分布本身抖动（缓解：H 只在档位间切换、加滞回；优先保 p99 稳定而非平均最快）；批处理增加单次等待（缓解：接触段禁用批处理）。

```python
class FastLeg:  # 前端；每步 <1ms；不含任何任务策略
    def __init__(self, dt, joint_lo, joint_hi, v_max, m_min, support_poly):
        self.prev_a = None
        self.last_safe = None
        self.cfg = dict(dt=dt, lo=joint_lo, hi=joint_hi, v_max=v_max,
                        m_min=m_min, poly=support_poly)

    def step(self, s_t, chunk, phase, t_since_plan):
        # 1) 参考动作：chunk 内取 A_phi；用尽则线性外推/保持
        if t_since_plan < len(chunk):
            ref = chunk[phase]
        else:
            ref = extrapolate_or_hold(self.last_safe, chunk[-1], phase)
        a = ref.copy()

        # 2) 约束检测（经典视觉 + 本体，不学习任务策略）
        c = self.constraints(s_t, a)  # {stability, joint, velocity, human, contact}

        # 3) 无约束：向参考收缩（不重规划语义）
        if c.human:
            a = self.hold_and_retreat(s_t)          # I4
        else:
            if c.stability:
                a = self.project_stability(s_t, a)  # I10
            if c.contact:
                a = self.contact_reflex(s_t, a)     # I3
            if c.joint:
                a = np.clip(a, self.cfg["lo"], self.cfg["hi"])
            if c.velocity and self.prev_a is not None:
                a = self.limit_velocity(a, self.prev_a, self.cfg["v_max"])

        a = self.action_health(a)  # 离群/平滑/NaN 检查
        self.prev_a = a
        if not c.human:
            self.last_safe = a
        return a
```

### 2.2 尾延迟感知调度 + 弹性 chunk

```python
class TailLatencyScheduler:
    def __init__(self, H0=8, Hmin=1, Hmax=30, Lstar=None, eta=1, hyst=0.1):
        self.H = {}; self.L = {}          # 每端口独立
        self.H0, self.Hmin, self.Hmax = H0, Hmin, Hmax
        self.Lstar = Lstar; self.eta = eta; self.hyst = hyst

    def on_latency(self, port, L):
        self.L.setdefault(port, []).append(L)
        p = p99(self.L[port][-200:])
        # AIMD：p99 高 -> 增大 H（少调用）；低 -> 减小 H（提反应）
        if p > self.Lstar * (1 + self.hyst):
            self.H[port] = min(self.H.get(port, self.H0) + self.eta, self.Hmax)
        elif p < self.Lstar * (1 - self.hyst):
            self.H[port] = max(self.H.get(port, self.H0) - self.eta, self.Hmin)

    def dispatch(self, port, obs, deadline):
        # deadline-aware 批处理：等待窗口不超过最紧 deadline
        wait = min(self.batch_window, deadline - now())
        batch = self.collect(port, wait)           # 每端口状态隔离
        return self.backend.run(batch)             # 共享 6B 后端并发执行
```

|---|---|---|---|
| L0-pivot | 零/保持/安全投影，离线回放 32k eps 的臂伸展—重心相关性 | 免费 | 保持不劣于零；安全投影仅降低裕度违规率、不显著改变动作 |
| L0-ego | 自运动增广前后动作一致性 | 免费 | 未见/位置轴动作一致性提升，标称不退化 |
