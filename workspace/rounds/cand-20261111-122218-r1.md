# 第 55 轮（承接第 54 轮 v16 GroundEdge-GenSim+++；灵感循环第 1 轮；本轮灵感：「个性化交互」×「具身智能」）

> 第 54 轮完成了动作空间剖面 α_S、技能组合图与云边联合证书 J。本轮把镜头从「技能能否组合」推进到「为谁、以什么身体去组合」：个性化交互要求系统面向具体用户做条件化，具身智能要求一切策略落到具体身体与感知回路上。核心矛盾：**H22**：个性化通过收窄交互分布换取偏好匹配，但收窄会压缩鲁棒性余量并把动作推出具身包络；**H23**：具身包络是硬物理约束，未经具身接地的个性化会产生「偏好被满足、身体做不到」的假个性化。

## 0. 直觉与动机

**灵感 1（个性化 = 用户条件下的鲁棒性，而不是另一套系统）**
直觉：个性化不该是「给每个用户训练一个专用模型」，而应视为在鲁棒性谱上增加一个条件维度 u：`ρ(d | u)`。同一技能对不同用户、不同交互风格 s 的有效鲁棒性不同。若把个性化看成条件的加入，则第 53–54 轮的全部证书都可被「用户条件化」复用，而不必推倒重来。关键量是 **个性化增益** `G_u(π)=E_{π}[U_u]-E_{π_0}[U_u]`：不是「像不像这个用户」，而是「相对通用策略到底多解决了什么」。

**灵感 2（具身包络 = 动作剖面的硬边界）**
直觉：第 54 轮的 α_S 定义了技能「愿不愿意/能不能」覆盖动作，但没定义身体「允不允许」。具身智能要求增加 **包络 E=(A_body, Φ_sense, C_morph)**：可达关节动作、传感映射、形态学成本（能耗、磨损、限位）。个性化风格 s 会隐含一组动作需求 `ground(s)`（例如「高主动性」要求快速移动、「高解释粒度」要求多模态输出），只有 `ground(s) ⊆ A_body` 才算具身可落地。**具身包络把个性化从偏好空间拉回物理空间。**

**灵感 3（专业化-鲁棒性张力：个性化越强，越像过拟合）**
直觉：个性化必然提高特异性、降低交互分布熵，而鲁棒性余量通常随分布熵下降而收缩。把这条张力显式化成 Pareto 前沿 `(spec, m)`：`spec` 为专业化程度，`m` 为最差维度鲁棒裕度。存在「鲁棒性悬崖」：越过某点，偏好满足度略升而鲁棒性骤降。**好的个性化是前沿上的膝点，不是偏好最优点。** 更危险的是「对单个用户过拟合」：换用户、或同一用户偏好漂移 ε 后性能崩塌，需 **反事实用户鲁棒性** 来检验。

**灵感 4（个性化-具身联合证书 PIC）**
直觉：既然个性化是用户条件、具身是物理边界，证书就必须同时承诺三件事：① 在用户偏好球内仍鲁棒（反事实用户鲁棒性）；② 所需风格动作落在具身包络内（具身接地误差 Δ_s）；③ 个性化增益不是靠仿真-现实缝隙骗来的（增益校准 β_G）。于是得到 PIC `P_u=(u,π_u,E_cert,ρ_u,G_u,P_CF,Δ_s,evidence,consent)`，比第 54 轮 J 多出用户维与身体维。

**灵感 5（金字塔再加两层：𝕌 用户层、𝔼 具身层，以及跨具身迁移）**
直觉：在第 54 轮动作-协同层 𝔸 之上再叠 `𝕌`（用户偏好与交互风格）与 `𝔼`（具身包络与传感），并引入 **跨具身个性化迁移 XET**：同一用户偏好在不同身体之间搬运时，用共享交互语义潜变量 z 做中介，迁移成本 `c_xet` 同时计入结果分布距离与形态差。证书跨身体传递时，ρ 与 A_cert 必须随 E 重估，不能直接继承。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（个性化交互剖面与个性化增益）**
用户 `u` 在结果空间 `O` 上有效用 `U_u: O→ℝ` 与偏好测度 `μ_u`；交互风格空间 `S`（主动性、节奏、模态、解释粒度）。技能 S 在风格 `s∈S` 下的交互剖面 `β_{S,s}^u: O→[0,1]` 为结果分布。个性化策略 `π_u` 满足
```
π_u = argmax_π  E_{o~β_π^u}[U_u(o)] - λ·KL(π ‖ π_0)
```
其中 `π_0` 为通用策略，λ≥0 控制个性化强度。**个性化增益** `G_u(π)=E_{o~β_π^u}[U_u(o)] - E_{o~β_{π_0}^u}[U_u(o)]`。用户偏好球 `B_ε(μ_u)={μ : W_1(μ,μ_u) ≤ ε}`。

**定义 122（具身包络）**
具身包络 `E=(A_body, Φ_sense, C_morph)`：`A_body⊆A` 为身体可达动作；`Φ_sense: A→O` 为感知映射；`C_morph: A→ℝ_+` 为形态学成本。可执行性 `emb(a)=1[ a∈A_body ∧ C_morph(a)≤c_max ]`。风格 s 的动作接地 `ground(s)={a | s 隐含需要 a}`，**具身接地条件** `ground(s) ⊆ A_body`，接地误差 `Δ_s = max_{s∈supp(π)} dist(ground(s), A_body)`。

**定义 123（个性化-具身可行域）**
```
F_u = { π | supp(π) ⊆ ground^{-1}(A_body),
            ρ_π(d | u) ≥ ρ_min ∀ d∈𝔇,
            G_u(π) ≥ G_min,
            H(π) ≥ H_min }
```
`H` 为交互分布熵，`H_min` 防止个性化坍缩成单一行为。若 `F_u=∅`，判定**个性化不可满足**，必须回退到带解释的通用策略 `π_0`，不得强行个性化。

**定义 124（专业化-鲁棒性张力与鲁棒性悬崖）**
专业化程度 `spec(π)=1 - H(π)/log|O|`；鲁棒裕度 `m(π)=min_{d∈𝔇}(ρ_π(d|u)-ρ_min)`。Pareto 前沿
```
P* = { π | ¬∃π' : spec(π')≥spec(π) ∧ m(π')≥m(π)（至少一严格）}
```
**鲁棒性悬崖**为 `m(π)<0` 的可行域外区域。个性化选择规则：在 `P*` 上取膝点 `π_u = argmax_{π∈P*} spec(π)` s.t. `m(π) ≥ κ·m_max`，`κ∈(0,1]` 为保守系数。

**定义 125（个性化交互证书 PIC）**
```
P_u = (u, π_u, E_cert, ρ_u, G_u, P_CF, Δ_s, evidence, consent)
```
- `E_cert=(A_body_used, c_morph_max, sensor_coverage)` 为具身包络符合证书；
- `ρ_u(d)=ρ_π(d|u)` 为用户条件化鲁棒性谱；
- `P_CF = min_{μ∈B_ε(μ_u)} G_u(π_u; μ)` 为反事实用户鲁棒性（偏好漂移下的最差增益）；
- `Δ_s` 为风格接地误差；
- `evidence` 至少包含该具身的仿真反例与（可行的）小样本真机试验；
- `consent` 为用户级适配/数据使用的同意记录。
**可部署条件**：`F_u≠∅ ∧ Δ_s≤Θ_s ∧ ρ_u≥ρ_min ∧ P_CF≥G_min`。

**定义 126（跨具身个性化迁移 XET）**
交互语义编码 `z=enc(o,s)`。把 `π_u^{E1}` 迁移到 `E2` 得 `π_u'^{E2}`，迁移成本
```
c_xet = W_1(β_{π_u}^{E1}, β_{π_u'}^{E2}) + w_m·||E1-E2||_morph + w_s·KL(z^{E1}‖z^{E2})
```
迁移证书要求 `c_xet ≤ τ_x ∧ ρ^{E2}(d|u) ≥ ρ_min ∀d`。跨具身不得直接继承 ρ 与 A_cert，必须按 `E2` 重估。

## 2. 关键算法 伪代码

### IP-121 PUP（Personalized User Profile / 主动偏好引出）

```python
def elicit_profile(user, outcomes, budget):
    mu, sigma = prior(user)
    for _ in range(budget):
        pair = argmax_pair(outcomes, info_gain(mu, sigma))
        choice = query(user, pair)          # 容忍非传递偏好
        mu, sigma = bayes_update(mu, sigma, pair, choice)
    return Profile(mu, sigma, U=fit_utility(mu))
```

### IP-122 EEP（Embodiment Envelope Projection）

```python
def project_to_embodiment(pi, ground, E, delta_lost_budget):
    delta_s = max(dist(ground(s), E.A_body) for s in support(pi))
    if delta_s > Theta_s:
        return ('reject', 'embodiment_gap', delta_s)
    pi_e = {a: p for a, p in pi.items() if emb(a, E)}
    lost = 1.0 - sum(pi_e.values())
    if lost > delta_lost_budget:
        return ('reject', 'action_loss', lost)
    return ('ok', normalize(pi_e))
```

### IP-123 PPC（Personalization-Pareto Certification）

```python
def pareto_certify(candidates, user, kappa):
    front = pareto(candidates, key=lambda p: (spec(p), margin(p, user)))
    max_m = max(margin(p, user) for p in front)
    feasible = [p for p in front
                if margin(p, user) >= kappa * max_m and margin(p, user) >= 0]
    if not feasible:
        return ('reject', 'robustness_cliff')
    return ('ok', max(feasible, key=spec))
```

### IP-124 CUR（Counterfactual User Robustness）

```python
def counterfactual_robustness(pi_u, mu_u, eps, rho_min):
    worst_G, worst_rho = inf, inf
    for mu in wasserstein_ball(mu_u, eps, n=64):
        G = gain(pi_u, mu)
        rho = robustness(pi_u, mu)
        worst_G, worst_rho = min(worst_G, G), min(worst_rho, rho)
        if worst_rho < rho_min:
            return ('fragile', 'user_overfit', mu)
    return ('ok', worst_G) if worst_G >= G_min else ('fragile', 'gain_collapse')
```

### IP-125 PIC（Personalized Interaction Certificate）

```python
def personalize_certificate(user, skills, E, eps):
    profile = elicit_profile(user, outcomes, budget=64)
    pi = personalize(profile, skills)
    ok, pi_e = project_to_embodiment(pi, ground, E)
    if ok != 'ok':
        return ('reject', 'embodiment', pi_e)
    status, P_CF = counterfactual_robustness(pi_e, profile.mu, eps, rho_min)
    if status != 'ok':
        return ('reject', 'counterfactual', P_CF)
    rho_u = estimate_spectrum(pi_e, user)
    if min(rho_u.values()) < rho_min:
        return ('reject', 'robustness', rho_u)
    E_cert = (E.A_body_used, max(C_morph(a) for a in support(pi_e)), E.sensor_cov)
    return ('ok', PIC(user.id, pi_e, E_cert, rho_u, gain(pi_e, profile),
                      P_CF, delta_s=grounding_error(pi_e), consent=user.consent))
```

### IP-126 XET（Cross-Embodiment Transport）

```python
def transport(pi_source, E1, E2, tau_x):
    z = encode_interaction(pi_source)
    pi_t = decode_for_embodiment(z, E2)
    c = wasserstein(pi_source, pi_t) + w_m * morph_dist(E1, E2) + w_s * kl(z1, z2)
    if c > tau_x:
        return ('reject', 'transport_gap', c)
    rho2 = estimate_spectrum(pi_t, E2)
    if min(rho2.values()) < rho_min:
        return ('reject', 'robustness_loss', rho2)
    return ('ok', TransportCert(pi_t, c, rho2))
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| PUP | O(B·|O|·log|O|) | O(|O|) | 偏好后验校准、非传递偏好容错 |
| EEP | O(|π|·|A_body|) | O(|A_body|) | 包络保守、投影损失可计量 |
| PPC | O(|Π|·|𝔇|) | O(|Π|) | Pareto 完备、悬崖检测 |
| CUR | O(K·|π|·|𝔇|) | O(K) | 漂移球覆盖、最差情形可算 |
| PIC | O(B·|O| + |π||A| + K|𝔇|) | O(|A|+|𝔇|) | 四条件闭合 |
| XET | O(|π|·|E2| + |O|²) | O(|O|²) | 语义潜变量对齐、重估 ρ |

**正确性定理（Personalized-Embodied Deployment Soundness）**
假设第 54 轮 (A26)–(A28) 成立；新增 **(A29)** 偏好后验校准且偏好漂移 `W_1≤ε`；**(A30)** 具身包络 `(A_body,C_morph)` 估计保守；**(A31)** 个性化增益的仿真-现实偏差 `|G_u^{sim}-G_u^{real}|≤β_G`。则
```
P_success ≥ 1 - P(F_u=∅) - P(Δ_s>Θ_s) - Σ_d(1-ρ_min(d))
            - P(W_1(μ,μ_u)>ε) - β_G - β_E
```
正确性要点：**个性化只在 F_u 内生效；鲁棒性按用户条件化；漂移球内做反事实校验；增益必须扣除仿真-现实偏差。**

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 偏好引出欠采样/非传递 | 高 | 信息增益选点 + 非传递偏好模型 + 后验校准 |
| 具身包络 sim-to-real 偏差 | 高 | 保守包络 + 真机小样本锚定 + 安全停机 |

| 个性化公平性受损 | 中高 | 少数用户最差增益约束 + 分层重加权 |

## 6. 本轮最大风险

**一句话**：个性化交互与具身智能把「技能组合」推进到「为具体用户、在具体身体上成立」，但其 soundness **三重依赖偏好后验校准、具身包络保真、以及偏好漂移下的反事实鲁棒**；一旦过度个性化把策略推过鲁棒性悬崖或具身包络，系统会交付「偏好被满足但身体做不到 / 换个用户就崩」的假个性化，故必须以 **CUR 反事实护栏 + κ 鲁棒悬崖约束 + 保守具身包络** 三重保险，宁可弱个性化，绝不以用户过拟合换取表面增益。

# 第 55 轮产物 · 创新点清单 v32：GroundEdge-GenSim++++（PUP×EEP×PPC×CUR×PIC×XET）

> 承接第 54 轮产物 v31。本轮在动作-鲁棒性双证书体系之上，增加 **用户条件化** 与 **具身包络** 两个第一性维度，形成 v32：
> - **PUP（Personalized User Profile）**：预算受限的主动偏好引出，输出可校准偏好后验；
> - **EEP（Embodiment Envelope Projection）**：把个性化策略投影到身体可达动作集，量化具身接地误差；
> - **PPC（Personalization-Pareto Certification）**：在专业化-鲁棒性 Pareto 前沿上取膝点，防止越过鲁棒性悬崖；
> - **CUR（Counterfactual User Robustness）**：在偏好漂移球内做最差情形校验，识别用户过拟合；
> - **PIC（Personalized Interaction Certificate）**：用户 + 具身 + 鲁棒 + 增益四条件联合证书；
> - **XET（Cross-Embodiment Transport）**：经交互语义潜变量的跨身体个性化迁移证书。
>
> IP 编号：IP-121~IP-126（共 6 个新增），升级 IP-115/117/118/120 以纳入用户条件 u 与具身包络 E。

```python
    delta_s = max(dist(ground(s), E.A_body) for s in support(pi))
    if delta_s > Theta_s:
        return ('reject', 'embodiment_gap', delta_s)
    pi_e = {a: p for a, p in pi.items() if emb(a, E)}
    lost = 1.0 - sum(pi_e.values())
    if lost > delta_lost_budget:
        return ('reject', 'action_loss', lost)
    return ('ok', normalize(pi_e))
```

### IP-123 PPC

```python
def pareto_certify(candidates, user, kappa):
    front = pareto(candidates, key=lambda p: (spec(p), margin(p, user)))
    max_m = max(margin(p, user) for p in front)
    feasible = [p for p in front
                if margin(p, user) >= kappa * max_m and margin(p, user) >= 0]
    if not feasible:
        return ('reject', 'robustness_cliff')
    return ('ok', max(feasible, key=spec))
```

### IP-124 CUR

```python
def counterfactual_robustness(pi_u, mu_u, eps, rho_min, G_min):
    worst_G, worst_rho = inf, inf
    for mu in wasserstein_ball(mu_u, eps, n=64):
        G = gain(pi_u, mu)
        rho = robustness(pi_u, mu)
        worst_G, worst_rho = min(worst_G, G), min(worst_rho, rho)
        if worst_rho < rho_min:
            return ('fragile', 'user_overfit', mu)
    return ('ok', worst_G) if worst_G >= G_min else ('fragile', 'gain_collapse')
```

```python
def personalize_certificate(user, skills, E, eps):
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| PUP | O(B·|O|·log|O|) | O(|O|) | 后验校准、非传递偏好容错 |
| EEP | O(|π|·|A_body|) | O(|A_body|) | 包络保守、投影损失上界 |
| PPC | O(|Π|·|𝔇|) | O(|Π|) | Pareto 完备、悬崖可判 |
| CUR | O(K·|π|·|𝔇|) | O(K) | 漂移球最差情形可算 |
| PIC | O(B·|O|+|π||A|+K|𝔇|) | O(|A|+|𝔇|) | 四条件闭合 |
| XET | O(|π|·|E2|+|O|²) | O(|O|²) | 潜变量对齐、ρ 重估 |

**正确性定理（Personalized-Embodied Deployment Soundness）**
假设第 54 轮 (A26)–(A28) 成立；新增 **(A29)** 偏好后验校准且 `W_1(μ,μ_u)≤ε`；**(A30)** 具身包络估计保守；**(A31)** `|G_u^{sim}-G_u^{real}|≤β_G`。则
```
P_success ≥ 1 - P(F_u=∅) - P(Δ_s>Θ_s) - Σ_d(1-ρ_min(d))
            - P(W_1(μ,μ_u)>ε) - β_G - β_E
```
关键：**个性化只在 F_u 内生效**，**鲁棒性按用户条件化**，**漂移球内做反事实校验**，**增益扣除仿真-现实偏差**。

## 5. 与第 54 轮证书的关系

第 54 轮联合证书 `J=(ρ,A_cert,γ_ce,δ_a,evidence)` 在本轮被 **两层条件化**：
```
J ⊂ P_u
P_u = J | (u, E)  ⊕  (G_u, P_CF, Δ_s, consent)
```
即：PIC 不是替换 J，而是把 J 放到「用户条件 × 具身包络」下重估，并追加反事实增益与同意字段。任何跨用户/跨身体复用都必须显式重估 `ρ_u`、`A_cert`、`Δ_s`，否则证书失效。

## 6. 本轮最大风险

**一句话**：个性化交互与具身智能把「技能组合」推进到「为具体用户、在具体身体上成立」，但其 soundness **三重依赖偏好后验校准、具身包络保真、以及偏好漂移下的反事实鲁棒**；一旦过度个性化把策略推过鲁棒性悬崖或具身包络，系统会交付「偏好被满足但身体做不到 / 换个用户就崩」的假个性化，故必须以 **CUR 反事实护栏 + κ 鲁棒悬崖约束 + 保守具身包络** 三重保险，宁可弱个性化，绝不以用户过拟合换取表面增益。
