### 第 6 轮灵感驱动研究记录（本轮循环第 1 轮）

**灵感词**：数据集、Gazebo

**继承关系**：承接第 5 轮 CADVS-v5（IP-493~496，Certified Generative Execution, CGE）：七硬门 fail-closed、证书不变性（定理 6）、调制单调性（定理 5）、固化有界（定理 7）、执行集 Exec_CADVS-v5 ⊆ … ⊆ Exec_v29。v5 有三个尚未偿还的结构性短板：(a) 所有证书都建立在「数据」上，但数据本身不是信任对象——来源、覆盖、污染、泄漏、同意、时效、DP 预算均未验证，属「garbage in, certified garbage out」；(b) 实验是「单机仿真」的口头结果，没有形式化测试台、场景覆盖度量与可复现的反例搜索，仿真证据不可审计；(c) sim-to-real 差距未量化，仿真通过不能作为真实安全证据。两个灵感词统一为主题「认证的数据与仿真闭环」（Certified Data & Simulation Loop, CDSL），形成 CADVS-v6（IP-497~500）。本轮自律：**轨迹层硬门仍为七**；数据集与仿真作为「元证据层」约束可信参数域 Θ_cert，而非新增逐轨迹门。执行集嵌套升级为 Exec_CADVS-v6 ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29。

**直觉与动机**：

1. **数据集 → 把数据升格为一等信任对象，证书从「模型」下移到「数据版本」**。v5 的流策略 θ_FM、阈值校准、记忆原型、FER 校准全由数据产生；若数据被投毒、跨集泄漏、标签漂移、授权过期，则下游所有证书在语义上都是空的。引入 DPCK：每个数据集版本 D 有内容寻址清单 h(D)（Merkle 哈希链 + 签名），数据集证书 D-cert(D) = (来源溯源、覆盖度、标签质量、污染/泄漏检测、同意与许可、时效、DP 预算)。关键设计：D-cert 在**数据集版本边界**求值（离线/低频），不在每条轨迹上求值；部署的每个 θ 必须引用一个通过 D-cert 的清单哈希，「无证数据 → 无证参数 → 禁止部署」（模型级 fail-closed）。第二个用法：数据集不是被动资产，而是**主动覆盖工具**——用门边界附近的不确定度驱动主动采集/合成（coverage-driven active data acquisition），优先补齐最可能让门判错的区域。这与 v5 的固化闭环互补：固化解决「经验如何反哺策略」，DPCK 解决「经验本身可不可信」。

2. **Gazebo → 从「演示仿真」升级为「认证测试台 + 反例锻造器」，并用外部结局 oracle 打断 v5 的自指回路**。Gazebo（ROS 2 + 物理插件 + 传感器噪声模型）提供闭环场景执行。构建 GSTH：场景 DSL（物体/几何/摩擦/光照/传感器故障/人因事件）、覆盖度量（场景覆盖、门边界覆盖、接触模态覆盖）、自动反例搜索（在仿真中搜索「形式门通过但结局违背」的轨迹）、回归套件。认识论上必须诚实：**仿真只能证伪，不能证实**——Gazebo 找到的反例是有效的反驳（Popperian falsification），仿真通过只给出覆盖下界，不构成真实安全证明。但 Gazebo 提供了一个 v5 缺失的东西：**独立于证书门的结局 oracle**（任务成功/碰撞/滑落/人因伤害），从而把 v5-R57 的「铸证→学习→再铸证」自指闭环打开一个外部锚点——策略可以博弈门，但难以同时博弈一个它看不到的结局 oracle。

3. **Gazebo 的 sim-to-real → 用保形预测给仿真证据一个可迁移的统计界**。仿真证据要能迁移到现实，必须量化差距。S2RC：在配对数据（真实机器人日志 vs Gazebo 重放）上校准 sim2real 差距，用保形预测（conformal prediction）给出结局偏差 δ 的 1−α 覆盖上界；只有当 δ_{1−α} ≤ δ_max 时，仿真通过才允许作为「真实通过的下界证据」；否则仿真只保留证伪权。域随机化 + 系统辨识用于缩小差距，但差距本身作为一等指标上报，而不是隐藏。

**关键洞见**：v5 回答「提议是任意生成器、记忆反哺、人因含情感时，证书边界如何保持不变」；v6 回答「证书所依赖的证据从哪来、验证它的测试台可不可信」。数据集负责**证据溯源与覆盖**，Gazebo 负责**独立结局 oracle 与反例搜索**，S2RC 负责**证据迁移的统计界**。七硬门 kc_evidence_forged_v5 记号原样复用；本轮新增的只有：数据集证书 D-cert、可信参数域 Θ_cert、仿真覆盖/反例算子、sim2real 保形界 δ_{1−α}。执行集 Exec_CADVS-v6 ⊆ Exec_CADVS-v5 由「同门 + θ ∈ Θ_cert + 反例剔除区域」三重保证。

**形式化目标（增量）**：
1. DPCK = (P_prov, D_cert, Cov_data, Contam, Leak, Consent, Fresh, Δ_active)；D-cert(D) ∈ {0,1}；h(D) 内容寻址。
2. GSTH = (DSL, Exec_gz, Cov_scen, Oracle_out, Falsify)；覆盖下界 Cov(S_test, S_target) ≥ 1−ε_scen。
3. S2RC：配对校准集 → 保形上界 δ_{1−α}；迁移条件 δ_{1−α} ≤ δ_max。
4. Θ_cert = {θ : D-cert(D_θ)=1 ∧ δ_{1−α} ≤ δ_max ∧ sim 回归通过}；只有 Θ_cert 中的 θ 可部署。
5. 定理 9（数据/参数分离与执行集不变性）、定理 10（仿真证伪可靠性）、定理 11（sim2real 保形迁移界）、定理 12（七锚完备性 + 外部 oracle 打断自指）。
6. Exec_CADVS-v6 = {x ∈ supp(π_θ^FM) : θ ∈ Θ_cert ∧ ∧_i kc_i(x,c; γ_i·τ_i^4)=1 ∧ x ∉ Falsified} ⊆ Exec_CADVS-v5。

**本轮最大风险**：**数据—仿真同源共谋（co-construction circularity）**——训练数据、记忆原型、校准集与测试场景都由同一个 Gazebo 世界模型及其同一套建模误差生成，测试通过只证明「与仿真器自洽」；保形界又只在配对分布内有效，真实世界的 OOD 仍无界；数据溯源只能证明「来源可查」，不能证明「数据真实、无偏、无投毒」。这会把 v6 变成一台「仿真内自我确认」的机器。

## 2. 关键算法骨架

### IP-497 DPCK：数据溯源与策展核（离线/版本边界；不进入逐轨迹执行集）

```python
@dataclass
class DatasetProvenanceCurationKernel:
    """DPCK：数据集作为一等信任对象。
    红线：D-cert 在数据集版本边界求值，只约束 Θ_cert，不改变轨迹层门谓词"""
    ledger: ProvenanceLedger          # Merkle 哈希链 + 签名，内容寻址
    coverage: CoverageEstimator
    contam: ContaminationDetector     # 与评测/红队集交叉泄漏 + 近重复检测
    consent: ConsentRegistry
    dp_budget: DPBudgetLedger
    eps_cov: float = 0.05
    tau_leak: float = 0.01
    t_fresh: float = 90 * 24 * 3600

    def certify(self, D: DatasetVersion) -> DatasetCertificate:
        prov = self.ledger.verify(D.manifest_hash)          # 哈希链 + 签名完整性
        cov = self.coverage.lower_bound(D, target_scen)     # ε-覆盖下界
        leak = self.contam.cross_leak(D, eval_sets)         # 与评测集泄漏率
        ok = (prov.valid
              and cov >= 1 - self.eps_cov
              and leak <= self.tau_leak
              and self.consent.all_granted(D)
              and self.dp_budget.remaining(D) >= 0
              and (now() - D.collected_at) <= self.t_fresh)
        return DatasetCertificate(pass_=ok, manifest_hash=D.manifest_hash,
                                  provenance=prov, coverage=cov,
                                  leak_rate=leak, reasons=self._reasons(...))

    def acquire(self, gate_uncertainty: GateUncertainty) -> AcquisitionPlan:
        """覆盖驱动主动采集：按门边界不确定度排序，而非随机采样。
        目标：最大化 Cov_data 增量 / 采集成本；隐私预算进入目标函数"""
        ...
```

### IP-499 S2RC：sim-to-real 校准核（配对数据 + 保形界）

```python
@dataclass
class Sim2RealCalibrationKernel:
    """S2RC：配对 sim/real 校准 + 保形 sim2real 差距上界。
    保形只给边际覆盖，OOD/条件保证无——诚实边界"""
    alpha: float = 0.05
    delta_max: float = 0.05

    def calibrate(self, paired: list[Pair]) -> float:
        # 交换性假设下的 split-conformal：分数 = |sim_outcome - real_outcome|
        scores = [abs(p.sim_outcome - p.real_outcome) for p in paired]
        return conformal_quantile(scores, 1 - self.alpha)          # δ_{1-α}

    def transfer_ok(self, delta: float) -> bool:
        return delta <= self.delta_max

    def usable_as_lower_bound(self, delta: float) -> bool:
        """仅当 δ≤δ_max 时，仿真通过才可作真实通过的下界证据；
        否则仿真只保留证伪权（反例仍然有效）"""
        return self.transfer_ok(delta)
```

### IP-500 EFA-v6：七硬门 + 可信参数域 + 证伪剔除

```python
@dataclass
class EvidenceForgingAssemblerV6:
    """EFA-v6：门集合不变；数据集/仿真只约束 Θ_cert 与支撑集"""
    v5: EvidenceForgingAssemblerV5
    dpck: DatasetProvenanceCurationKernel
    gsth: GazeboScenarioTestHarness
    s2rc: Sim2RealCalibrationKernel
    theta: Any
    falsified: Any                    # Falsified 区域/反例集

    def deploy(self, theta, D_theta) -> tuple[bool, str]:
        cert = self.dpck.certify(D_theta)
        delta = self.s2rc.calibrate(self.paired)
        if not cert.pass_:
            return False, 'UNCERTIFIED_DATA'          # 模型级 fail-closed
        if not self.s2rc.transfer_ok(delta):
            return False, 'SIM2REAL_GAP_TOO_LARGE'
        if not self.gsth.regression(self.v5):
            return False, 'SIM_REGRESSION_FAILED'
        self.theta = theta
        return True, 'THETA_CERTIFIED'

    def select(self, x0_state, t_now, rule_id, context):
        # 复用 v5 全流程（FAMK 调制、FMPP 提议、级联选证）
        ok, x, reason = self.v5.select(x0_state, t_now, rule_id, context)
        if not ok:
            return False, None, reason
        if x in self.falsified:                        # 只缩支撑，不改门
            return False, None, 'FALSIFIED_BY_GAZEBO'
        return True, x, 'FORGED_CDSL'

    def ecs_v6(self, n_flow, s_emo, D_theta, delta) -> float:
        eta_data = 1.0 if self.dpck.certify(D_theta).pass_ else 0.0
        eta_sim = (1.0 if self.s2rc.transfer_ok(delta) else 0.0) * \
                  self.gsth.coverage(self.suite)
        return self.v5.ecs_v5(n_flow, s_emo) * eta_data * eta_sim
```

| GSTH.falsify | O(B·T_sim·n_dof) | O(B) rollout 缓存 | B=10³–10⁴, T_sim=10 s | 离线/夜间，小时级 |
| GSTH.coverage | O(\|S_test\|·d_scen) | O(\|S_test\|) | — | 离线，秒级 |
| S2RC.calibrate | O(n_pair log n_pair) 排序 | O(n_pair) | n_pair~500–2k | 离线，分钟级 |
| Θ_cert 校验 | O(1) 哈希查表 | O(1) | — | < 0.01 ms |
| EFA-v6 增量 | O(1)（布尔剔除 + 常量因子） | O(1) | — | 控制环不变，< 0.03 ms |
| 端到端在线 | 与 v5 同（~0.6 ms 控制环 + 异步准入） | — | — | 不新增实时负担 |

**通信开销**：认证清单根哈希与 D-cert 摘要 ~1 KB/模型版本；覆盖/差距指标 ~百字节级低频上报；配对 sim/real 数据仅本地校准，原始数据不出站；DP 预算账本随联邦统计聚合。

**对 v5-R59（条件接口漂移）的偿还**：D-cert 的 manifest 哈希把「数据版本—条件 schema—策略权重」三者绑定为不可分三元组，schema 变更必须触发数据清单与回归套件重认证，版本负债从隐式变显式。

## 4. 正确性论证（增量更新）

### 引理 45（场景覆盖下界）

**陈述**：设场景空间 S_target 可被有限网格/占位划分为 N 个单元，S_test 在每单元至少采样 m 次，则对任意有界结局函数 f（值域 [0,1]），以概率 ≥ 1−δ 有 |E_{S_target}[f] − E_{S_test}[f]| ≤ √(log(2N/δ)/(2m))。∎

**诚实边界**：覆盖是相对离散化/度量而言的；高维连续场景空间的覆盖证书依赖度量选择，存在「覆盖了网格但漏掉对抗流形」的风险。

### 引理 46（污染检测功效界）

**陈述**：若投毒样本比例 ≥ ρ 且与干净样本在检测特征上总变差 ≥ TV_min，则检测器以 ≥ 1−exp(−n·KL_lower) 的概率告警（Sanov/ Chernoff 界）。低于 ρ_min 的稀疏投毒可逃逸检测，D-cert 只提供统计保证而非确定性保证。∎

### 引理 47（保形覆盖保证）

**陈述**：若配对校准样本与待测 episode 可交换，则 split-conformal 给出 P(|sim_outcome − real_outcome| ≤ δ_{1−α}) ≥ 1−α（边际覆盖）。**不提供**条件覆盖与 OOD 覆盖。∎

### 定理 9（数据/参数分离与执行集不变性）

**陈述**：设轨迹层门谓词 kc_i 与阈值 τ^4 冻结，DPCK 只通过 Θ_cert 限制可部署 θ，则对任意 D-cert 升级，Exec_CADVS-v6 = {x ∈ supp(π_θ^FM) : θ∈Θ_cert ∧ ∧_i kc_i=1 ∧ x∉Falsified} ⊆ Exec_CADVS-v5。数据升级只能改变提议支撑与校准，不能放宽门谓词。

**证明**：Exec_v5 = {x ∈ supp(π_θ^FM) : ∧_i kc_i=1}（v5 定义）。v6 在同门谓词上增加 θ∈Θ_cert 与 x∉Falsified 两个合取约束，故为 v5 的子集；D-cert 本身不出现在逐轨迹谓词中，换数据不换谓词。∎

### 定理 10（仿真证伪的可靠性与其边界）

**陈述**：(i) 若 Gazebo 找到 x 使仿真中 ∧_i kc_i(x)=1 且 oracle(x)=FAIL，则「门通过 ⇒ 安全」在 Gazebo 转移模型下被证伪（可靠反驳）。(ii) 该反驳迁移到真实世界，需要反例的违背边际 margin(x) > 2δ_{1−α}，否则可能由 sim2real 噪声解释。(iii) 仿真通过（无反例）**不**蕴含真实安全，只给出相对覆盖下界。

**证明**：(i) 构造性反例即反驳。(ii) 若真实违背量 = 仿真违背量 ± δ，则 margin>2δ 时符号不被噪声翻转。(iii) 证伪逻辑的否定不对称：无counterexample ≠ 全称命题为真。∎

### 定理 11（sim2real 证据迁移界）

**陈述**：在引理 47 的交换性假设下，且 δ_{1−α} ≤ δ_max 时，仿真通过可作为真实通过的下界证据，其边际置信 ≥ 1−α；若 δ_{1−α} > δ_max，则仿真证据只保留定理 10 的证伪权。**该保证为边际的、非条件的，对真实 OOD 无界。**

**证明**：保形覆盖 + 差距界三角不等式；OOD 破坏交换性，故保证失效。∎

### 定理 12（七锚完备性与外部 oracle 打断自指）

**陈述**：v6 不增删轨迹层锚点，七锚 {3DCF, MSRG, HICK, EEK, LTEM, VACK, BCK} 完备性（v4 定理 4）保持；Gazebo oracle 不是新锚，而是测试时的外部结局信号，不进入执行集谓词。若 oracle 与门判定在统计上独立（不同信息源），则 v5-R57 的门博弈率被 oracle 检出率下界约束：gaming_rate_effective ≤ gaming_rate_raw·(1 − det_oracle)。**独立性与 det_oracle 均为经验量，无先验保证。**

**证明**：锚点集合不变 + 定理 9 的支撑收缩；博弈有效通过 = 原始博弈通过 ∧ oracle 未检出，取补集得界。∎

## 5. 实验设计与初步结果（Gazebo 仿真 + 小规模真机配对；舰队/大规模实机列入第 7 轮）

### 5.1 实验设计

- **平台**：Gazebo Harmonic + ROS 2 Jazzy（机械臂 + 移动操作）；真实配对数据来自 6-DoF 桌面机械臂（~500 条配对 episode）；流策略/记忆/FER 沿用 v5 权重并重新按 D-cert 审计。
- **数据集变体**：D1 干净仿真集；D2 仿真+真机混合；D3 注入 2% 定向投毒（门边界错误标签）；D4 与评测集 15% 交叉泄漏；D5 过期/同意缺失集。
- **对照**：v5-full、v6-full、消融 B1（v6 去 D-cert）、B2（v6 去 Gazebo oracle，仅仿真自洽）、B3（把仿真通过当真实证明，去 S2RC）、B4（随机采集 vs 覆盖驱动采集）。
- **场景**：(a) 数据投毒/泄漏注入下的证书与部署行为；(b) Gazebo 反例搜索（门边界 + 接触模态）；(c) sim2real 差距扫描（摩擦/质量/延迟失配）；(d) 门博弈红队（沿用 v5 对抗集）；(e) 覆盖驱动采集的边际收益。
- **指标**：D-cert 检出率/AUROC、错误部署阻断率、场景覆盖下界、反例召回率、δ_{1−α}、真机成功率、门博弈有效通过率、覆盖/成本比、认证开销。

| 风险编号 | 描述 | 严重度 | 缓解措施 | 剩余风险 |
|---|---|---|---|---|
| R19–R59 | v1~v5 全部既有风险 | — | 随原版继承；R57 由 Gazebo 外部 oracle 部分打断 | 见既有表 |

## 7. 本轮最大风险（最终确认）

**一句话**：**数据—仿真同源共谋**——训练数据、记忆原型、校准集与测试场景都由同一个 Gazebo 世界模型及其同一套建模误差生成，测试通过只证明「与仿真器自洽」；保形界又只在配对分布内有效，真实世界的 OOD 仍无界；数据溯源只能证明「来源可查」，不能证明「数据真实、无偏、无投毒」——这会把 v6 变成一台「仿真内自我确认」的机器。
