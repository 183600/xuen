# 第 71 轮（承接第 70 轮「BELIEF-RAS 贝叶斯状态估计层」IP-264~274；新灵感循环第 1 轮；本轮灵感：「跌倒恢复」×「对话管理」）

> R70 把闭环补成「显式信念」：`b_t(s)`、`H[b_t]` 成了 epistemic 的真身，交互从单次 VoI 变成贝叶斯实验设计，并配了基线协议与原型验证。但 R70 仍隐含两个从未被检验的假设，而它们恰好在本轮两个灵感处同时崩塌：
> 1. **状态连续、安全集单一、动作可微**。跌倒是一次**离散相变**：接触流形、动力学、可用动作集一起突变；R70 的单一安全包络在「我已经倒了」之后无定义，`b_t` 的先验与观测模型也瞬间作废。真正的安全不是「静态稳定」，而是「我还能不能从这儿起来」——**可行性核（viability kernel）是相位相对的**。
> 2. **交互是单轮、开环、无限时限**。R70 的 MINT 选一个信息动作就执行；真实恢复需要**多轮对话管理**：先问「哪条腿被卡住」，再确认「你让我推的是你的左边还是我的左边」，答案不自洽时要**修复**，还要在硬恢复窗口内决定「继续问」还是「先撑起来再说」。
>
> 核心命题：**「跌倒恢复」与「对话管理」是同一件事的物理面与符号面——都是「当前计划/假设已经失效后，如何按阶段、带接地、有时限地从失效中恢复」。** 将 R70 的单一交互升级为**恢复对话策略**，将单一安全集升级为**相位索引的可行性核族**，并用「对话只能改变信念、不能改变物理可行性」这条分离原则守住安全。命名 **RECON-RAS**（REcovery-CONversation，双关 reconnaissance：以对话为侦察手段的恢复闭环）。
>
> 一句话定位：R68 问「测量还准吗」，R69 问「该问谁」，R70 问「我相信什么」，R71 问「**当我已经倒下——身体倒了，或信念倒了——我怎样一步步重新站起来？**」

## 0. 直觉与动机

**灵感 1（跌倒恢复 → 安全不是一个集合，而是一族相位索引的可行性核）**
直觉：R68–R70 的 `λ_floor` 与安全包络都假设「一个连续、时不变的可行域」。可跌倒本身就是动力学模式的跳变：站立（双足支撑）→ 半跪（膝+手）→ 俯卧（多接触）是三个不同的混合系统。判断「我现在能不能起来」，不是看重心是否落在支撑多边形内（那是静态稳定，俯卧也稳定），而是看**是否存在一条从当前状态出发、在力矩/热/时间约束内能到达下一相位的受控不变轨迹**。这就是 viability kernel。把它写成相位索引：安全不是 `S`，而是 `{V_φ}`；一次恢复是穿越 `{V_φ}` 的一条路径，**只有当前状态落在下一相位的可行性核里，才允许承诺相位切换**。这把安全从「别倒」升级为「倒了也能受控地起，且绝不进入不可恢复的死角」。
反思 R70：`H[b_t]` 只说「我对状态有多不确定」，却不区分「不确定但可恢复」与「不确定且已进入不可恢复集」。RECON 把 **`b_t(V_φ)`（后验落在下一相位可行性核内的质量）** 提升为一等公民——它比 `H[b_t]` 更接近生存本身。

**灵感 2（对话管理 → 恢复是一段有轮次、有接地、有确认、有修复的对话）**
直觉：R69/R70 的交互是「单轮开环」：选一个 `g`，执行，更新，结束。真实恢复几乎从不这样。人扶机器人时会说：「你哪边卡住了？」「我推你左肩行吗？」「等等，别动，我先挪开椅子。」这里有**对话状态跟踪**（对方知道多少、接地到哪）、**对话行为**（询问/确认/请求/致谢/终止）、**轮次管理**（一次只做一件事，等对方回应）、**接地**（双方对指称与坐标系达成一致）、**修复**（对方回答与现状矛盾时，追问而不是丢弃）。R70 的 CIA 在证据冲突时只能「不定案」，对话管理却能「追问一个更精确的问题把冲突解掉」——这把交互从「采样证据」升级为「**协议化的共同恢复**」。
最锋利的落地难点（也是本轮最好的具体例子）：**坐标系接地**。机器人俯卧时，「推左边」在机器人自身坐标、人类自身坐标、世界坐标下是三个不同方向；一句「左边」若接地错误，恢复动作会把人或机器人推倒。这不是世界状态不确定，而是**指称/框架不确定**，R70 的 `b_t(s)` 根本装不下它。

**灵感 3（时限 → 信息有保质期，恢复对话必须是 anytime 的）**
直觉：恢复有硬窗口——关节过热、电池耗尽、二次损伤、社交耐心都随时间恶化，而对话本身耗时间。所以 VoI 必须按剩余恢复时间折价：**截止期之后才到的信息，价值为零**。更关键的是，恢复不必「先问完再做」：可以**边撑边问**——先做一个属于当前相位可行性核、且安全余量为正的动作，同时把问题抛出去；答案及时到就用它选下一相位，不到就按保守序列继续。这把 R69 的「看—问—做」从串行改造成**带截止期的交错执行**，也是「对话管理」在物理系统上的独特形态：既要 turn-taking，又不能真的停下来等。

**灵感 4（修复 → 对话管理的灵魂，而不是 R70 的「不一致就不动」）**
直觉：R70 的 k-正交一致纪律是「防守型」的：不一致 → 不定案 → 保守。对话管理的核心恰恰是「进攻型修复」：不一致说明**解释模型**错了，去找「哪一处解释能让两边都成立」——是坐标系反了？是「左腿」指错了？还是「别推左腿」被听成了「推左腿」？然后针对那一点问一个**最小充分问题**。这给出可证明的终止条件：每次修复把解释歧义集的熵至少降 `Δ_rep`，故修复轮数有上界；超过上界或成本超预算，就退回保守/求助。这把 R69 的「问错比不问更危险」从「禁止问」变成「**问得更准，并知道何时停**」。

**灵感 5（双重失效 → 最大的风险是「看起来站起来了」）**
直觉：恢复过程本身会造成二次伤害（自碰撞、过力矩、再次倾覆），而对话会把机器人**从「诚实的不知道」推向「被对方确认过的错误」**。当人类出于好意给了错误指令、或机器人错误接地了「左/右」，系统会自信地执行一个动力学上不可行、或方向相反的恢复动作——表面上完成了对话流程，实际上进入了更深的不可恢复状态。所以本轮必须交付：相位可行性证书（对话无权越过 `V_φ`）、接地/确认门、修复深度上限、以及「恢复剧场」检测（动作序列符合脚本但当前接触状态不满足其前提 → 立即中止）。最大风险不是「摔了」，而是「**用一场成功的对话，证明了一个致命的错误**」。

## 1. 形式化定义（增量：定义 331–349）

**定义 331（RECON-RAS 总览）** RECON-RAS = (FMP‡, VKR, DMR, DVS, RGC, AUD‡, J_RECON)。四不变式：
(i) **实时流零学习写操作**（继承 R68 定义 276-i）；
(ii) **多轮累计预算**：交互预算在多轮上累计（不是单轮），每轮须过与任务动作相同的认证；
(iii) **相位分离原则**：对话/交互只更新 `b_t` 与接地状态 `γ,κ`，**绝不修改可行性核 `V_φ` 或安全集**——物理可行性是对话不可谈判的；
(iv) **升级版证据纪律**：承诺相位切换需同时满足 (a) `b_t(V_{φ'}) ≥ 1−δ_v`、(b) 至少一个正交证据源或确认轮一致、(c) 修复深度未超 `k_rep`。

**定义 332（恢复相位混合自动机）** 相位 `Φ = {φ_0 俯卧/跌倒, φ_1 自检/支撑, φ_2 推起/跪, φ_3 起身, φ_4 站立/验证}`。转移 `e=(φ,φ')` 带 guard `G_e = (x∈V_{φ'}) ∧ (belief 条件) ∧ (机械/热预算 OK)`。恢复是相位路径 `ρ = φ_0→…→φ_4`，带每相位时限 `T_φ` 与总窗口 `T_rec`。这是混合自动机；与 R68 的连续控制不同，跳变处必须显式认证。

**定义 333（可行性核 `V_φ`）** `V_φ = { x∈S_φ : ∃π_u, ∀w∈W，轨迹保持在安全集 S_φ 内，且在 T_φ 内以概率 ≥1−ε_v 到达 guard G_{φ→φ'} }`。离线预计算每相位的 reachability/viability 表，在线只查表并计算 `b_t` 的质量。

**定义 334（恢复可行性证书 RGC）** 候选转移 `e` 的证书 `RGC(e) = ( b_t(V_{φ'}), 最坏扰动下可达概率下界, 力矩/热余量, 自碰撞检查, 失败回退相位 φ_safe )`。`RGC(e)=Pass ⇔ b_t(V_{φ'})≥1−δ_v ∧ 下界≥1−ε_v ∧ 余量>0 ∧ 回退∈V_φ`（回退本身可行）。**对话不能把 Fail 变 Pass**（定义 331-iii）。

**定义 335（恢复对话状态）** `d_t = (b_t, γ_t, κ_t, φ_t, f_t, τ_t)`。`γ_t` 接地状态（ungrounded / proposed / grounded / contradicted）；`κ_t` 人类知识状态估计（对方知道什么、是否理解）；`φ_t` 当前已承诺相位；`f_t` 坐标系/指称框架 `∈ F = {robot-ego, human-ego, world}`；`τ_t` 轮次与剩余时限。

**定义 336（对话行为集）** `A_d = {ask_state(θ), confirm(e), request_help(part,dir), repair(q), acknowledge, terminate}`。每个行为带语义 `π_ans(y|s,d)` 与成本 `c_d(·)`（时间 + 社交 + 认知负荷）。

**定义 337（恢复对话策略 DMR）** `π_dm(a_d|d_t)`，目标最大化 `E[1{恢复成功} − Σ成本 − 二次伤害惩罚]`，受 turn-taking（一轮一个未决行为）、时限、修复深度约束。实现为 POMDP 上的 receding-horizon 规划（人时间尺度，异步于控制环）。

**定义 338（接地自动机）** `γ` 对一次指称/框架表述从 ungrounded→proposed；对方确认/纠正后→grounded 或 contradicted。接地置信 `g_conf = P(指称正确|交互历史)`。**执行方向性物理动作前须 `g_conf ≥ 1−δ_g`**。

**定义 339（框架不确定性）** 「左/右/前/后/推/拉」在每个 `f∈F` 下有不同 referent。引入框架后验 `p(f|d_t)` 与框架熵 `H_F = H[p(f)]`。这是独立于 `H[b_t]` 的第二类 epistemic：**世界状态不确定 vs 指称框架不确定**。R70 的 `b_t(s)` 不含 `f`。

**定义 340（截止期感知 VoI）** `VoI_τ(g) = E[ 1{t_ans ≤ T_rec−t} · (H[b_t]−H[b_{t+1}]) ]`，即把信息价值按剩余窗口折价。若 `t_ans` 分布已知，`VoI_τ` 关于剩余时间单调不增；剩余时间→0 时 `VoI_τ→0`。

**定义 341（边做边问的交错调度 DVS）** 每轮允许复合动作 `(u_phys, a_d)`，其中 `u_phys` 必须落在当前相位 `V_φ` 内且安全余量 `≥ ε_brace`；并行推进物理恢复与对话。仅当不存在安全 `u_phys` 时才阻塞等待。

**定义 342（修复算子）** 解释歧义集 `ℐ = {指称/框架/单位/否定的可能解释}`。当证据与 `b_t` 矛盾（似然比 `< ρ_rep`），repair 选问题 `q* = argmax_q E[减少 H[ℐ]] − c_d(q)`，把 `ℐ` 收缩到与所有已观测证据一致的最小子集。修复深度上限 `k_rep`；超限 → 转 `request_help` 或保守序列。

**定义 343（确认门）** 对任何不可逆/高风险相位转移 `e`，需 `confirm(e)` 得到人类明确一致回应，或 `b_t(V_{φ'})` 与 `g_conf` 同时超阈值。确认只提高信念，不改变 `V_φ`。

**定义 344（恢复剧场检测）** 若执行序列在运动学上符合脚本，但当前接触/姿态不满足脚本前提（前提似然 `p<τ_theater`），判定「恢复剧场」，立即转 `φ_safe` 并重估 `b_t`。防止「看起来很对的站起来」。

**定义 345（二次伤害风险）** `R_2nd = E[自碰撞 + 过力矩 + 再倾覆 + 对人施力超限]`。恢复相位内不仅用 `λ_recon` 缩放速度，还约束**每相位动作集** `A_φ = {u∈A : 该相位下 R_2nd 上界 ≤ ε_2nd}`。

**定义 346（审计 VQAuditor-III）** 审计：相位承诺是否有 RGC、对话是否过接地/确认门、修复是否超深、是否出现恢复剧场、以及「对话/确认是否被用来掩盖物理不可行性」。

**定义 347（干扰集 AIC‡）** `ℰ_RECON = ℰ_BELIEF × ℰ_fall（错误跌倒模式诊断/接触估计偏差）× ℰ_dialog（错误指称、框架翻转、恶意/善意误导、确认偏差、延迟回答）× ℰ_theater（恢复剧场/脚本前提失配）`。

**定义 348（证书 J_RECON）** `J_RECON = (J_BELIEF, phase_path, RGC_hash_each, grounding_conf_min, repair_depth, dialog_turns, deadline_regret, theater_flag, recon_ver)`。Valid ⇔ 每跳 RGC=Pass ∧ 接地门满足 ∧ 修复未超限 ∧ 无未解释 theater。

**定义 349（对 R70 的包含关系）** 无跌倒（`Φ={φ_4}`）、单轮（`k_rep=0, τ=∞`）、无框架歧义（`|F|=1`）时，RECON 逐指令退化为 BELIEF。R70 是 RECON 在「永不失效」边界上的退化。

# IP-276 VKR：相位可行性核查表 + 恢复证书
class ViabilityKernelRecovery:
    def __init__(self, kernels, guards):          # 离线预计算 V_phi
        self.V, self.G = kernels, guards

    def certify(self, e, b_t, budget, robot_state):
        phi, phi2 = e
        mass   = integrate(b_t, self.V[phi2])                 # b_t(V_phi2)
        reach  = self.G[e].worst_case_lower_bound(robot_state, budget)
        margin = check_torque_thermal_collision(robot_state, e)
        fallback_ok = self.V[phi].contains(fallback_state(e))
        ok = (mass >= DELTA_V and reach >= 1 - EPS_V
              and margin.ok and fallback_ok)
        return Cert(ok, mass, reach, margin)                  # 对话不能改 ok

    def select_transition(self, b_t, phi, budget):
        cands = [e for e in out_edges(phi) if self.certify(e, b_t, budget).ok]
        return min(cands, key=lambda e: self.expected_cost(e, b_t))

# IP-279 DMR：恢复对话策略（POMDP，receding horizon，人时间尺度）
class RecoveryDialogueManager:
    def act(self, d):                              # d = (b,gamma,kappa,phi,f,tau)
        if not self.turn_taking_ok(d): return Wait()
        best = None
        for a_d in build_dialog_acts(d):           # ask/confirm/request/repair
            if not self.grounding_gate(d, a_d): continue
            val = self.expected_value(d, a_d)      # 成功 - 成本 - 二次伤害
            if best is None or val > best.val: best = (a_d, val)
        if best is None or best.val <= self.wait_value(d):
            return self.fallback_conservative(d)   # 不问，保守/求助
        return best.a_d

    def repair(self, d, contradiction):
        if d.repair_depth >= K_REP: return RequestHelp()
        q = argmax(set_of_repairs(d), key=lambda q:
                   expected_entropy_drop(d, q) - cost(q))
        return q                                   # 最小充分问题

    def grounded_and_confirmed(self, d, e):
        return (d.g_conf >= 1 - DELTA_G) and (
            (not e.risky) or d.confirmed.get(e, False))

# IP-280 FGR：框架后验与接地
def update_frame_posterior(d, utterance, referent):
    lik = {f: p_lexical(utterance, referent, frame=f) for f in FRAMES}
    d.p_f = normalize({f: d.p_f[f] * lik[f] for f in FRAMES})
    d.g_conf = max(d.p_f.values())                 # 接地置信
    return d

# IP-277 DVS：截止期感知交错调度（边撑边问）
def deadline_aware_step(M, d, brace_candidates):
    u = safest_in_phase(brace_candidates, d.phi, eps_brace=EPS_BRACE)
    a_d = M.dmr.act(d) if remaining_time(d) > T_MIN else None
    y   = M.dmr.dispatch_async(a_d) if a_d is not None else None
    return (u, a_d), y

# IP-289 主闭环
def RECON_round(M, obs):
    b_t = M.bse.step(M.b_prev, obs, ...)           # R70
    phi_hat, fall_mode = M.fall.diagnose(obs, b_t)
    if phi_hat == PHI_STAND:
        return BELIEF_RAS_round(M, obs)            # 正常路径逐指令退化为 R70
    d = M.dmr.init_dialog(b_t, phi_hat)
    while not M.deadline.expired(d) and d.phi != PHI_STAND:
        e = M.vkr.select_transition(d.b_t, d.phi, d.budget)
        cert = M.vkr.certify(e, d.b_t, d.budget, M.state)
        if not cert.ok:                            # 不可行：修信念或求助
            a_d = M.dmr.repair_or_help(d, cert)
            y = M.dmr.execute(a_d); d = M.dmr.update(d, a_d, y); continue
        if e.risky and not M.dmr.grounded_and_confirmed(d, e):
            a_d = M.dmr.ask_or_confirm(d, e)       # 方向性动作前必须接地
            y = M.dmr.execute(a_d); d = M.dmr.update(d, a_d, y); continue
        (u, a_d), y = deadline_aware_step(M, d, M.policy.phase_actions(d))
        exec_control(u)                            # 只执行 V_phi 内的安全步
        if y is not None: d = M.dmr.update(d, a_d, y)
        if M.theater.suspect(d, u):                # 恢复剧场
            d = M.dmr.abort_to_safe(d); continue
        d.phi = e[1]                               # 仅证书 Pass 才推进相位
        d.b_t = M.bse.step(d.b_t, obs, u, a_d, y)
    return M.vkr.stand_verify(d) if d.phi == PHI_STAND else M.safe_wait(d)

## 3. 推导

**引理 23（静态稳定 ≠ 可恢复；`V_φ` 是严格更细的安全对象）** 存在状态 `x` 使 COM 投影落在支撑多边形内（静态稳定），但 `x ∉ V_φ`（关节限位/低电量/被卡住/接触不可控），从 `x` 出发任何控制都无法在 `T_φ` 内到达 `G`。故仅用 R68–R70 的单一安全集或静态稳定判据，会承诺一个不可恢复的相位；以 `V_φ` 为约束的恢复控制器在安全侧严格更保守（更大安全集的安全）。系：**「能站起来」是比「没倒下」更强的安全概念**。

**引理 24（截止期 VoI 单调折价 + 交错支配）** (i) `VoI_τ(g)` 关于剩余时间单调不增，`T_rec−t→0` 时 `→0`，故时限耗尽时 RECON 自动退化为 R70 的不交互保守。(ii) 若存在 `u∈A_φ` 且安全余量 `≥ε_brace`（有正价值的撑起准备），则「执行 `u` 同时异步发问」的期望回报 ≥「阻塞等待回答」（阻塞白耗窗口且未降低风险）。系：**能边做边问时不要停下来等**。

**引理 25（修复的熵下降与有界轮数）** 若每次矛盾属于「框架/指称型」且存在一个最小充分问题把 `ℐ` 的某一切分消掉，则每轮修复使 `H[ℐ]` 至少降 `Δ_rep>0`；因 `H[ℐ] ≤ log|F|`，修复轮数 `≤ ⌈log|F|/Δ_rep⌉`。超限仍矛盾 ⇒ 不是解释错误而是世界模型错误，应转 `request_help`/保守，而非继续问。这给 R70 的「证据纪律」补上了终止论据。

**引理 26（多轮确认把投毒上界再压一层）** 在 R69 引理 18（k 源一致，错误率 `≤ δ_p ρ^{k−1}+ε_σ`）之上，对不可逆相位转移再加 confirm 轮且确认与原始回答的欺骗相关 `ρ_c<1`，则错误承诺率 `≤ (δ_p ρ^{k−1}+ε_σ)·ρ_c + ε_g`。且确认只作用于 `g_conf`，不改变 `V_φ`——**即使确认被攻破，物理可行性证书仍拦截**。系：安全有两条独立闸门（物理 + 社会），任一守住即可。

**定理 20（RECON 严格包含 BELIEF 严格包含 R68）** 在 A102–A105（可行性核可计算且保守、截止期 VoI 单调、修复可辨识、确认独立）下，对任意状态期望风险 `R(RECON) ≤ R(BELIEF) ≤ R(R68)`；且在「无跌倒 / 单轮 / τ=∞ / |F|=1」边界三者逐指令相同。

**定理 21（恢复安全与分离原则）** 若所有相位切换 `e` 都满足 `RGC(e)=Pass`，则恢复轨迹在 `T_rec` 内以概率 `≥1−K·ε_v` 保持在各相位安全集内、且不进入不可恢复集；对话/确认/修复只改变 `b_t, γ, κ`，不改变 `V_φ`，故**任何对话结果都不能授权一个物理不可行的相位转移**；修复超限/超时/接地失败时，相位选择单调退化到保守序列（停留/求助）。

**定理 22（anytime 时限后悔界）** 若在 `t` 时刻截止期到达且答案未返回，回退到保守序列的期望遗憾 `≤ V_max·P(t_ans > T_rec−t) + L_theater·P(theater)`。系：**截止期不是失败，只是退回更保守的可行策略**——RECON 的安全性不依赖对话成功。

def certify_transition(M, e, b_t, budget, rstate):

    mass = integrate(b_t, M.V[phi2])                 # b_t(V_phi2)

## 4. 推导（工程可测版）

**引理 23（可恢复性细于静态稳定）** `V_φ ⊆ S_φ` 且存在 `S_φ∖V_φ` 非空（关节限位/低电量/被卡/接触不可控）。故只用静态稳定会承诺不可恢复相位。系：验收必须测"进入 `S∖V` 的次数"，而不是只测倾角。

**引理 24（截止期折价 + 交错支配）** `VoI_τ` 单调不增；存在正安全余量的撑起动作时，"边做边问"期望回报 ≥ "阻塞问"。系：控制环永远不因等答案而空转。

**引理 25（修复有界）** 每次框架/指称型修复使 `H[ℐ]` 至少降 `Δ_rep`，轮数 `≤ ⌈log|F|/Δ_rep⌉`；超限转求助。系：对话不会无限循环，审计可用 `repair_depth ≤ k_rep` 直接判违规。

**引理 26（双闸门）** 社会闸门（确认）与物理闸门（RGC）独立；确认投毒上界在 R69 引理 18 上再乘 `ρ_c`，但即使社会闸门失守，RGC 仍是硬约束。系：安全不依赖"人一定说真话"。

**定理 20（层层包含）** `R(RECON) ≤ R(BELIEF) ≤ R(R68)`；无跌倒/单轮/无框架歧义时逐指令相同。

**定理 21（恢复安全 + 分离原则）** 全部 `RGC=Pass` ⇒ 以概率 `≥1−Kε_v` 不进入不可恢复集；对话不能授权物理不可行转移；超时/超修复/接地失败单调退保守。

**定理 22（anytime 后悔界）** `regret ≤ V_max·P(t_ans>T_rec−t) + L_theater·P(theater)`；截止期不是失败，是更保守的可行解。

## 5. 复杂度与资源

| 组件 | 时间 | 空间 | 说明 |
|---|---|---|---|
| FPD 相位诊断 | < 0.5ms | O(1) | 控制环内 |
| VKR 转移枚举 + RGC | < 0.1ms/候选 | O(1) 查表 | 控制环内；`V_φ` 离线 |
| DVS 调度 | < 0.05ms | O(1) | 控制环内 |
| SHG/RTD 检查 | < 0.1ms | O(1) | 控制环内 |
| DST/DMR/FGR | 10–100ms/轮 | O(\|d\|) | **控制环外**，人时间尺度异步 |
| `V_φ` 离线构建 | 小时级，一次 | 每相位 MB 级 | reachability/viability 工具链 |
| 控制环总延迟 | **< 5ms** | — | 正常路径 ≈ R70 |

**接口契约（工程上最重要的一条）**：物理层与控制环只接受 `(u∈A_φ, RGC=Pass, 接地门满足)` 的三元组；对话层产出 `(a_d, y, d')` 并异步回写 `b_t,γ,κ,f`。两层通过一个**只读的 feasibility API** 交互——对话层查询"这个相位可行吗"，但**不能写回可行性**。这条契约让安全证明与对话学习解耦，避免"对话模型更新即安全回退"。

## 6. RECON-Baselines v1 与 RECON-Proto v1

**基线（固定种子/分割/指标/检验/模板）**
1. `R70-BELIEF`：无相位化恢复，单一安全集，单轮交互。
2. `Scripted-GetUp`：固定恢复脚本，不诊断、不对话。
3. `Stay-Down`：保持俯卧等待外力，绝对保守上界。
4. `Passive-Reset`：外部复位（遥操作/人工），性能上界参照。
5. `Human-Teleop`：全程人工，社交/人力成本上界。

**指标（6 维）**：恢复成功率、恢复时间、二次伤害率、危险动作放行率、对话轮数/打扰、进入 `S∖V` 次数。统计：10 种子 Wilcoxon `p<0.01` + Bonferroni；报告强制模板（含失败归因树）。

**验收（RECON-Proto v1）**
- 三环境：Isaac Sim（跌倒课程全覆盖）→ ROS 2（实时/异步）→ 真机（四足/人形，软硬地面、卡滞、人类干预）。
- 硬指标：控制环 P99 < 5ms；**危险动作放行 = 0**；`b_t(V_φ)` 证书误放行 ≤ 2%；接地 ECE < 0.05；三次连续跌倒恢复率 ≥ 85%；对照 R70 的恢复成功率显著提升（`p<0.01`）。
- 危险场景清单：俯卧被卡、侧翻窄缝、软地面、人类站错边、错误"左/右"、恶意错误指令、确认被共谋欺骗、恢复剧场（脚本前提失配）。

## 8. 本轮最大风险

**一句话**：全部安全收益取决于 `{V_φ}` 的建模保守性与 `b_t(V_φ)` 的校准——**一旦可行性核漏掉真实接触模式（软地面、被卡、被拉拽），或框架接地后验在人类含糊表述下过度自信，RECON 会用「接地正确、确认通过、RGC Pass」的完整流程，把机器人合规地推进不可恢复状态——这不是流程失败，而是流程太成功；故障被"合法的对话"掩盖，比没有对话更难诊断**。

**次级风险与缓解**
1. `V_φ` 离线→在线失配 → 在线可达性监测 + 保守回退相位 + 定期重标定；
2. 接地过度自信 → 方向性动作强制确认 + `g_conf` 校准门（ECE_ground）+ 失败即帧重估；
3. 对话社交工程 → 物理/社会双闸门 + `request_help` 施力包络 + 引理 26 上界；
4. 恢复剧场 → RTD 前提似然 + 每步中止 + `φ_safe` 重估；
5. 实时预算 → 对话全部异步、控制环仅查表；`V_φ` 离线、在线 O(1)。
