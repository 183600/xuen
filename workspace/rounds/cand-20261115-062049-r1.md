# 第 4 轮（研究线累计；灵感循环第 2 轮；本轮灵感：「角色一致性」×「多语言支持」）

> **基线**：第 3 轮 InstructGauge（IP-321–327；定义 432–447；引理 51–58；实验 E441–E456）。第 2 轮 ToolGauge、第 1 轮 LeanGauge / MODGAUGE 骨架继续原样继承。
> 本轮纪律：**增量升级 + 严格退化**。角色与语言各沿一条「证据—授权」轴升级 InstructGauge；任一环节不可用都必须能一键退回，角色一致性与多语言都是增强项、不是依赖项。

## 0. 直觉与动机

**灵感 1（角色一致性 → 不是「人格稳定」，而是「授权不漂移」）**
直觉：一个协作系统里，「角色」首先不是说话风格，而是**授权边界**——谁能提案、谁能批准、谁能执行、谁只能解释。角色一致性因此不是让机器人「保持人设」，而是让「谁被允许做什么」在整个会话里**可类型检查、可审计、不静默改变**。这里有三类真实失效：其一，**角色漂移**——长会话中系统从「建议」滑向「自主执行」，或人类用户的权限已过期却仍被沿用；其二，**角色坍塌**——提案者与批准者合并成同一角色，系统自证自批（self-approval），把「一致」变成了「共谋」；其三，**角色冒充**——某个语言里的角色标签被直接当作更高权限，文本本身成了提权通道。三者的共同点是：错误不在单个判断，而在**授权从证据里被悄悄推断出来**。所以正确口径是：授权只应来自**认证身份 + 角色状态机**，文本只能提出「角色请求」，不能授予角色。

**灵感 2（多语言支持 → 不是「多翻一遍」，而是「同一语义的多条证据 + 一条统一安全地板」）**
直觉：多语言最诱人的想法是「让模型多懂几种语言」，但安全性上真正的问题恰好相反：**最弱的那门语言决定系统被攻破的成本**。同一个危险请求，在高资源语言里被可靠拒绝，在低资源语言里却可能被误接地并通过——若只看平均指标，这个洞会被完全掩盖。因此多语言的价值应被拆成两件不同的事：其一，语言是**同一意图的第二条观测**，在类型化槽位上做跨语言一致性校验，能把单语言的偶然误接地压小；其二，语言也是**攻击面**，必须为每种语言提供**同一条安全地板**，弱语言下宁可「放弃/追问/请换语言」，绝不猜。关键结构是**语义核与表面实现的分离**：回执、约束、授权是语言无关的语义核；解释、追问、拒绝话术才是可本地化的表面实现。翻译只允许触碰表面，不允许触碰语义核。

**灵感 3（耦合 → 角色-语言一致性：授权不能从文本里长出来）**
直觉：把两者放在一起，最危险的耦合不是「翻译错一个词」，而是**翻译/改写把请求升格为更高权限**——低资源语言里一句「请主管确认去除涂层」，若被译成祈使句并被接地为「以主管权限执行」，系统就完成了一次**授权洗白（authority laundering）**。第二危险的是**最弱语言探针**：攻击者用多语言复述制造不一致版本，专门寻找最宽松的读法；若系统对关键槽做多数投票，它就会系统性地滑向「最不安全的那个翻译」。解法不是禁用多语言，而是四根结构支柱：**角色类型化 + 职责分离**（提案与批准不可同体）、**授权语言不变**（授权只由认证身份与角色状态给出）、**翻译不可授权**（翻译角色无 `Approve`，输出只是复述提案）、**最坏情形安全地板 + 跨语言一致性门**（关键槽分歧即否决，绝不取最宽松读法）。多语言与多角色由此从「两个模糊的增强项」变成两条可证伪的安全性质。

## 1. 研究问题（本轮要回答什么）

- **Q1（角色）**：角色一致性能否从「行为期望」变成「可类型检查的安全性质」？如何在长会话里检测并阻断角色漂移、角色坍塌（自证自批）与角色冒充，同时不把开销压到 50Hz 主路径上？
- **Q2（语言）**：跨语言的「同一语义」如何**可操作地**定义与验证？当低资源语言的接地能力更弱时，如何保证所有语言共享同一条安全地板，而不是被「平均值」掩盖出灾难性长尾？
- **Q3（耦合）**：多语言 × 多角色是否制造**授权洗白**（翻译/改写把请求升格）与**地板侵蚀**（攻击最弱语言）？能否用「角色类型 + 授权语言不变 + 最坏情形地板 + 跨语言一致性门」把风险压回可审计、可界、可退化？

## 2. 四条设计原则（雏形，正式化见产物区定义 448–463）

**P8 角色类型化与职责分离（Role Typing & Separation of Duties）**
每个模块/参与者只拥有一个角色契约 `Ω = (id, In, Out, Auth, Forbid)`：输入输出有类型、权限有集合、禁止项显式。硬不变式：**同一个动作的「提案」与「批准」不能由同一角色或同一证据链完成**（`Propose ∩ Approve = ∅`）。角色不是从文本里读出来的，而是从认证身份与角色状态机解析出来的；越权/歧义一律 `⊥`，冻结到单角色退化路径。这和第 3 轮能力闭包同构：**角色只做选择，不做能力扩张**。

**P9 授权语言不变（Language-Invariant Authority）**
对任意翻译/改写 `τ`，`auth(role, ℓ) = auth(role, τ(ℓ))`；授权函数 **不接受文本作为输入**。文本可以「请求」角色提升，但该请求只是 `escalation_request`，必须由已认证的更高角色显式批准，绝不能自我授予。任何「因为这句话看起来像主管说的」而获得的权限，都视为设计级失败。

**P10 最坏情形多语言安全地板（Worst-Case Multilingual Safety Floor）**
系统安全地板定义为 `min_λ (1 − ε_λ)`，**不是** `1 − Σ π_λ ε_λ`。新增一门语言只能保持或降低（不高于）原地板；弱语言必须**能力门控**：置信不足、校准样本不足或翻译不变证书失败时，选择放弃/追问/请换语言，绝不执行。平均安全是报告指标，最坏安全才是约束。

**P11 翻译不可授权（Translation Never Authorizes）**
翻译角色只有 `propose_paraphrase` 权限，`Approve = ∅`；其输出是带出处的**复述提案**，不得新增槽位、不得新增权限、不得有自由文本直达执行器。跨语言复述在**关键槽**（安全约束、优先级、工具、幅值、是否放弃）上必须一致；分歧是**否决**而不是投票，更不许取最宽松读法。语义核与表面实现分离：只有语义核进数值路径，表面实现只用于人机沟通。

## 3. 与基线的接口（如何退化）

- 角色契约缺失 / 角色歧义 / 违反职责分离 / 非静默点角色迁移 ⇒ 冻结到单角色（仅执行）路径，人工离线批准，等价于 InstructGauge；
- 翻译不变证书失败 / 关键槽跨语言分歧 / 角色标签试图提权 ⇒ 拒绝该复述，退回最佳单语言接地，必要时 `⊥ → ι₀`；
- 某语言校准样本不足或置信低于门限 ⇒ 层次收缩回退语言族阈值，再回退全局阈值（InstructGauge SC-Cal）；
- 角色变更发生在在途块内 ⇒ drain 到 `q_role` 或按 `abort` 截断并补偿，禁止跨权限的块；
- PolyGauge 失效 ⇒ InstructGauge ⇒ ToolGauge ⇒ LeanGauge ⇒ MODGAUGE 原样。

## 4. 预期贡献

1. 一个**角色类型化 + 职责分离**的安全口径，把「角色一致性」从行为期望变成可类型检查、可回放的性质，并给出长会话角色漂移/冒充的结构化阻断；
2. 一个**语言不变接地 + 翻译授权门 + 语义核/表面分离**的接口，把跨语言注入面压到「只能改表面、不能改授权」；
3. 一个**最坏情形多语言安全地板 + 语言分层共形校准**方案，修正「平均安全掩盖最弱语言」与「语言条件化破坏可交换性」两类统计失效；
4. 一条完整可证伪路径：E457–E472 覆盖职责分离、角色漂移、跨语言等价、翻译洗白、最坏语言地板、分层覆盖、角色-语言会话与 50Hz 时序。

## 5. 本轮最大风险

**一句话**：真正危险的不是「翻译错」或「角色标签错」，而是系统**把授权从文本/翻译里隐式推断出来**——一次低资源语言的翻译或一个伪造的角色标签，会在角色一致性检查「通过」的表象下完成授权升级，而这类错误既不会被语言层平均指标发现，也不会被单轮角色检查拦住，只能靠「授权只来自认证身份与角色状态」这条硬结构来阻断。

## 2. 形式化定义（要点）

**定义 448（角色契约 `Ω` 与角色系统）** `Ω = (id, In, Out, Auth, Forbid)`，其中 `In/Out` 是类型化接口，`Auth ⊆ A × Ctx` 是「动作 × 上下文」授权集合，`Forbid` 是显式禁令。一次调用 `f(args)` 合法当且仅当 `args ∈ In`、输出落在 `Out`、且 `(a,ctx) ∈ Auth`、`a ∉ Forbid`。`RoleSys = {Ω_i}` 为角色系统；7C 闭环的每个阶段被赋予**恰好一个**角色。角色身份由系统解析，**不由文本推断**。

**定义 449（权限偏序 `≤_auth` 与职责分离 SoD）** `≤_auth` 为 `Auth` 上的偏序。设 `Propose(a,e)` 为可对动作 `a`、证据 `e` 提案的角色集，`Approve(a,e)` 为可批准者集。**职责分离不变式**：`∀a,e: Propose(a,e) ∩ Approve(a,e) = ∅`，且不存在角色同时生成并签署同一证书。执行者不得撰写验证回执，解释者不得回写数值路径。这是「四眼原则」的类型级版本。

**定义 450（角色状态自动机 RSA 与角色漂移）** `Q_Role = (S_role, s_0, →, T_role, Revoke)`：迁移边由认证身份 `ID` 触发并记录；每个角色实例有有效期 `T_role` 与撤销集 `Revoke`。`q_role`（角色静默点）=「无在途块、无待处理不可逆动作、无未决角色请求」。**静默漂移**度量 `d_role(t) = D(role_state(t), role_state(t−1))`（状态/权限分布距离）；若 `d_role(t) > δ_role` 且无已认证迁移事件 ⇒ 冻结并要求重新认证。显式迁移与静默漂移被严格区分：前者是事件，后者是故障。

**定义 451（语言画像与语言分层）** `λ(ℓ) = (lang, script, family)`，`L` 为支持语言集，`π_λ` 为先验使用比例。校准分层键 `s_λ = (stratum(ι), family(λ))`（必要时可细到 `script`）。低资源语言按「校准样本数 `n_{sλ}` 与语言置信 `conf_λ`」操作性定义，而非按语种主观划分。

**定义 452（翻译、复述与类型槽等价 `≡_ι`）** `τ_{a→b}: L_a → L_b` 为翻译；回译为 `τ_{b→a}∘τ_{a→b}`；复述集成 `Para(ℓ) = {ℓ} ∪ {τ_b(ℓ)}_b ∪ {τ∘τ⁻¹(ℓ)}`。`ι₁ ≡_ι ι₂` 当且仅当所有**封闭槽**（目标 id、指代类、可测约束、预算、安全优先级、工具、幅值是否在包线、是否放弃）相等，且约束在可测谓词片段内逻辑等价；自由文本被投影掉，不参与等价判断。

**定义 453（翻译不变证书 TIC 与跨语言分歧）** `Crit(ι)` 为关键槽集（安全约束、`≻_safe` 优先级、工具、幅值、`abstain`）。`TIC(ℓ,τ) = (agree_crit, Δ_inv, evid)`，其中 `agree_crit = 1[∀c∈Crit: Γ(ℓ)|_c ≡_ι Γ(τ(ℓ))|_c]`，`Δ_inv = max_{c∈Crit} d_c(Γ(ℓ)|_c, Γ(τ(ℓ))|_c)`。**通过条件**：`agree_crit = 1` 且 `Δ_inv ≤ δ_inv`；否则 `⊥`。关键槽上**禁止多数投票**：分歧即否决，因为投票会系统性地倾向最宽松读法。

**定义 454（语言不变接地 `Γ_λ` 与放弃）** `Γ_λ: L_λ × Scene × O_onto → (ι, GroundCert, TIC) ∪ {⊥_λ}`。继承定义 432 的能力闭包（`tools(ι) ⊆ T₀`、`mag(ι) ⊆ M_phys`、无 free-text→actuator）。新增两条放弃条件：`conf_λ < τ_λ`（语言能力门控）或 TIC 失败 ⇒ `⊥_λ`。`⊥_λ ⇒ ι₀`（InstructGauge 默认目标），并**不**自动尝试更宽松语言来「凑一个可行解」。

**定义 455（翻译授权门 TAG 与授权增量）** 翻译角色 `Ω_T` 满足 `Auth(Ω_T) = {propose_paraphrase}`、`Auth(Ω_T) ∩ Approve = ∅`。其输出是 `(paraphrase, provenance)`，**不是** `ι`、更不是动作。授权增量 `AuthΔ(ℓ,τ) = Auth(Γ(τ(ℓ))) \ Auth(Γ(ℓ))` 必须为 `∅`；出现非空增量记 `Launder` 事件并拒绝。关键点：`Auth(·)` 的输入不含 `ℓ/τ`，所以洗白必须同时违反 TAG 与定义 458 才可能发生——两者都是类型级关卡。

**定义 456（语言分层共形校准 LSC）** 对每个 `s_λ` 取共形分位 `q_{s,λ}`，使层内覆盖 `P(h* ∈ H_{s,λ} | s,λ) ≥ 1−α`。样本不足时做**层次收缩**：`q_{s,λ} ← shr(q_{s,λ}, q_{family}, q_global; n_{sλ}, n_0)`，优先级 `语言层 → 语言族 → 全局`。收缩强度随 `n_{sλ}` 单调：`n_{sλ}→0` 时完全回退父层，`n_{sλ}→∞` 时收敛到语言层分位。

**定义 457（最坏情形安全地板 MLF 与能力门控）** 令 `ε_λ` 为语言 `λ` 下单位任务的误接地/注入成功风险。**安全地板** `Floor = min_{λ∈L}(1 − ε_λ)`；硬约束 `max_λ ε_λ ≤ ε_floor`。能力门控 `gate_λ = 1[conf_λ ≥ τ_λ ∧ TIC 通过 ∧ n_{sλ} ≥ n_min]`。`gate_λ = 0` 时系统**不执行**，只允许「放弃 / 追问 / 请换语言」。注意：`Floor` 对新增语言单调不增；平均安全 `1 − Σπ_λ ε_λ` 仅作报告。

**定义 458（授权解析 `Auth`：不来自文本）** `Auth(a,ctx) = f(ID, RoleState, Ω)`，其中 `ID` 经带外认证，`RoleState` 由 RSA 维护，`Ω` 是角色契约。**文本 `ℓ` 与翻译 `τ` 不是 `Auth` 的输入。** 文本可产生 `Request(role↑)`，但该请求只有在已认证的更高权限角色显式批准后才转化为迁移；`Request` 本身权限为零。这条是反授权洗白的公理。

**定义 459（RLCC 角色-语言一致性证书与账本）** `RLCC = (ID, role_id, auth_snapshot, λ, TIC, ι, C, receipts, claims, h_prev, h_self)`，其中 `h_self = H(前序字段 ‖ h_prev)`。账本 `Ledger` 仅追加（append-only）。任何被接受的动作必须具备完整链 `ID → role → auth → λ/TIC → ι → C → receipts → claims`；回放要么逐项复现，要么在哈希链处暴露篡改。`RepairCert′` 被扩展为含角色与语言字段。

**定义 460（角色条件分块 RCC）** 角色/权限歧义引入熵项 `κ_role = K·H(role | evidence)`（归一化后）。块长 `K ≤ K_MAX(ι,role) = ⌊K₀ / (1 + κ_sem + κ_role)⌋`。**角色变更屏障**：任何改变权限的已认证迁移都不得被单个块跨越；迁移前必须 drain 到 `q_role`，或按 `abort` 截断并补偿；权限迁移本身强制 `K=1`。直观：**不能用新权限去执行别人提案的旧块**。

**定义 461（语义核 / 表面实现分离 Sem/Surf）** `Sem(c)` 为证书导出、语言无关的语义内容（主张、拒绝理由、约束、回执绑定）；`Surf_λ(Sem)` 为语言本地化实现。只有 `Sem` 进入数值/验证路径，`Surf` 只用于显示与对话。拒绝与追问的**内容**由 `Sem` 决定，`Surf_λ` 只改变措辞——翻译不能借此新增任何主张。这把定义 441 的 NCB 从「主张↔回执」扩展到「主张↔回执↔语言表面」。

**定义 462（跨语言一致性门 XAG）** `XAG(ℓ, {τ_i}) = 1[∀i,j: Γ(τ_i(ℓ))|_{Crit} ≡_ι Γ(τ_j(ℓ))|_{Crit}]`。失败处理：关键槽 ⇒ `⊥`；非关键槽 ⇒ 取**最保守**槽（更受限的权限、更严格的约束、更小的幅值），**绝不允许取最宽松**。XAG 同时是「最弱语言探针」的结构性防御：攻击者提交互相矛盾的复述只会换来放弃，而不是最宽松读法。

**定义 463（PolyGauge 复合证书与 8C 闭环）** `PolyCert(s) = (RLCC, TIC, LSC stratum, floor_snapshot, receipts)`，用于端到端审计与覆盖核对。8C 闭环 `I→R→G→H→C→E→C→V→U`：`R` 解析角色与授权，`G` 做语言不变接地（替换原 `I`），其余阶段沿用 InstructGauge；每个阶段单角色、单一职责；热替换只发生在 `q_role ∩ q_quiesce`。

            return FROZEN                        # 未认证 ⇒ 单角色退化路径

## 4. 推导

**引理 59（角色类型化 ⇒ 无静默授权升级）** 在定义 448/449/458 下，沿任意良类型的调用链，权限只能通过**已认证迁移**增加；不存在从 `ℓ` 或 `τ` 到 `Auth` 的边。故任何被接受动作的授权都可追溯到初始认证角色集，且提案与批准不在同一角色/证据链上。*证明骨架*：对调用图做结构归纳。基础：初始角色的 `Auth` 由带外认证给定。归纳：若调用边不经 RSA 迁移，则被调方权限是调用方权限的子集（类型 + SoD 保证不增）；若经迁移，则迁移是显式、认证、记录的事件。文本只生成 `Request`，`Request` 无授权语义，故不产生边。职责分离排除「同一角色既提案又批准」的坍缩路径。

**引理 60（翻译不可授权 ⇒ 授权增量恒为 0）** 对任意 `ℓ,τ`，`AuthΔ(ℓ,τ) = ∅`；复述输出只能是原 `ι` 的**收紧**（槽位子集 + 更严格约束），不能放宽。*证明*：TAG 把翻译角色限制为 `propose_paraphrase` 且 `Approve = ∅`；`Auth` 不读文本（定义 458）；能力闭包（继承定义 432）保证不新增工具/幅值。三者合取下，任何非空 `AuthΔ` 必然对应同时违反 TAG 与 `Auth` 的实现缺陷，属类型级失败而非统计风险。推论：**授权洗白在结构上不可达**；残余风险只在实现正确性，由 E461/E469 主动证伪。

**引理 61（跨语言等价与「放弃优先于错译」）** 若 TIC 通过，则关键槽上 `Γ(τ(ℓ)) ≡_ι Γ(ℓ)`；若 TIC 失败，系统输出 `⊥_λ` 而非某个翻译的接地，因此**关键槽的有效错误率为 0（代价是放弃质量上升）**。非关键槽分歧取最保守值，不改变安全语义。*证明骨架*：`≡_ι` 在封闭槽上可判定；TIC 通过即逐槽相等；失败分支短路到 `⊥_λ`，由定义 454/462 不产生动作。代价项 `P(⊥_λ)` 随低资源语言能力上升，由 E460/E464 度量。

**引理 62（语言分层共形覆盖与层次收缩）** 层内可交换下，逐语言覆盖 `P(h*∈H_{s,λ} | s,λ) ≥ 1−α`；只在全局池化时，边缘覆盖下降 `≥ Σ_λ π_λ TV_λ + Δ_inv`（语言条件化破坏可交换性）。层次收缩后，低资源层覆盖满足 `Cov_{s,λ} ≥ 1−α − O(√(log(1/β)/n_{sλ})) − 2η_parent`，其中 `η_parent` 为父层分布漂移。*证明骨架*：层内共形保证；池化偏差由总变差三角不等式给出；收缩把 `n_{sλ}` 的有效样本数并入父层，故误差随 `n_{sλ}` 增大而消失。由 E463 检验。

**引理 63（最坏情形地板不可被平均掩盖）** `Floor = min_λ(1−ε_λ) ≤ 1 − Σ_λ π_λ ε_λ`，且存在语言使用分布使平均风险任意小、而某单一语言风险任意大。能力门控 `gate_λ = 0 ⇒ ε_λ^{exec} = 0`，故 `max_λ ε_λ^{exec} ≤ ε_floor` 当且仅当对所有非门控语言 `ε_λ ≤ ε_floor`。新增语言 `λ'` 只可能使 `Floor` 下降或不变。*证明骨架*：`min` 不超过任何加权平均；门控关闭时执行分支为空，执行风险为 0；`min` 对集合扩张单调不增。推论：**「支持更多语言」不能作为安全卖点，除非同步维护最坏地板**；这是 E462/E464 的核心判据。

**引理 64（RLCC 可审计性与回放一致性）** 每个被接受动作产生完整证据链 `ID→role→auth→λ/TIC→ι→C→receipts→claims`；在固定策略版本下回放账本复现同一授权决策；任何篡改以至少 `1−2^{-k}` 概率被哈希链检出（`k` 为哈希安全参数）。*证明骨架*：对账本追加做归纳；`h_self` 含 `h_prev` 形成链；篡改任一条目改变其后所有 `h_self`，与存储头不一致即检出。由此「角色一致性」从行为承诺变为**可回放的审计性质**。

**引理 65（角色条件分块与角色变更屏障）** 设角色歧义归一化熵为 `h_role`，在 `K ≤ K₀/(1+κ_sem+κ_role)` 下 `K·h_role < 1`，故「角色歧义 × 时间」不随 `K₀` 无界增长；权限迁移若跨块，则强制 `K=1` 或 drain 到 `q_role`，任何块都不会观察到两种权限。可逆部分损失仍为线性 `D_rev ≤ p_role Σ_i c_i`；不可逆部分继承 Barrier 与 `K` 解耦（引理 56）。*证明骨架*：与引理 56 的熵-块长不等式同构；角色迁移屏障把「混合权限块」从状态空间中删去；线性期望由逐块归纳给出。

**引理 66（降级等价与 50Hz 保全）** 关闭 RTC/RSA ⇒ 单角色路径，逐指令等价于 InstructGauge；关闭 LIG/TAG/LSC/MLF ⇒ 单语言（最佳支持语言或 `ι₀`）InstructGauge；所有新增检查都是异步路径上的短路守卫，主循环 `MODGAUGE_round` 不变。新增周期在缓存命中下 `< 0.2ms`；复述集成与翻译为异步、可缓存，最坏 `O(|L|·|ℓ|)` 但不进 50Hz 内联路径。未涉及子图的逐指令等价回到第 3 轮引理 57/58。*证明骨架*：按阶段删除做结构归纳；删去新增守卫后每个函数体退化为对应基线函数；复杂度由域分离与缓存给出。

## 8. 本轮最大风险

**一句话**：`LIG` 的跨语言接地与 `RSA` 的角色解析在接口处形成**授权洗白**——一次低资源语言的翻译或一个伪造的角色标签，会在 TIC/SoD 看似通过的情况下被隐式当作「更高权限的证据」，完成一次文本驱动的授权升级；缓解只能依赖硬结构（授权不读文本、翻译角色无 `Approve`、关键槽分歧即否决、最坏语言地板与能力门控）并以 E457/E461/E462/E469/E470 主动证伪。
