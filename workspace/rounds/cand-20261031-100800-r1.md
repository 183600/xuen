# 第 13 轮 · SCHEMA-WARP：把 33k 演示编译成多视角、物体相对的接触图式，用轻量证书补上 VLA 的最后 3 厘米

> 检索/复核日期：**2026-10-31（UTC）**。对象不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是灵感循环的新一轮，三个词是「**演示方案**」「**轻量化设计**」「**多视角视觉**」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是把 CHUNK-SERVO 的「检索一个相对位姿目标」升级为「**检索一条物体坐标系下的接触轨迹，并在执行前用多视角几何证书验一遍**」。

## 0. 这轮怎么想出来的：一条可复核的推理链

下面是我这轮的研究推理摘要，不是隐藏思维链；每一步都对应可检查的事实或可复现的实验。

1. **先复核事实，结果发现上一轮有两处关键错误。** 第一，上一轮写「腕部相机没有内参」是错的：`meta/info.json` 的 `camera_params.wrist_left.color.camera_matrix` 明确给出 `fx≈436.4, fy≈435.9, cx≈323.9, cy≈242.9`，右腕也有完整内参；真正缺的是腕相机到 EE 的**手眼外参**。第二，挑战赛 API 要求 `action.pivot[7]`，而官方 WLA 的 54 维动作里没有 `pivot` 槽；数据 README 给出的 pivot 定义是 `[vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]`，中间三维语义仍未公开。这两条都会改变方案，必须先写清楚。
2. **再看模型为什么都卡在 30% 附近。** 公开预览榜（未能复核，见 §1.6）头部约 30%；但不管具体数字，失败集中在你无法用「更大的 VLA」直接解决的地方：挂杯、插网线、插充电器、拉拉链、开锁、叠碗、倒药。它们不是语义问题，而是**最后 3 厘米的接触几何**问题。
3. **把「演示」从训练数据改成运行时记忆。** 33,276 条成功演示、169.28 小时、四路视角、30 fps，这不是只能拿来做 behavior cloning 的数据；它更是一本**按任务/阶段/物体坐标系索引的接触轨迹字典**。VLA 把所有演示压进权重，检索则可以把「这一条演示在这个物体上的最后 3 厘米」原样取出来。
4. **把「多视角」从输入改成验证信号。** 现有 VLA 把多视角当额外 token；官方 WLA 的训练配置甚至只用了 `head_left + 两个腕部`，右目没有进入 VLA。挑战赛 API 却给了四路图：头双目 + 双腕。头双目是**已标定的立体对**，可以恢复厘米级米制深度（精度有限，见 §2.2）；双腕给局部接触细节。多视角最大的价值不是「再编码一遍」，而是**互相校验**：单视角看起来对的轨迹，四视角必须同时解释得通。
5. **把「轻量化」理解成「不新增第二个学习模型」。** 单模型规则下，最安全的增量不是再训一个 4B/6B，也不是加一个学习残差，而是一个**确定性的运行时层**：检索、SE(3) 变换、多视角重投影、可见性/间隙检查、5 步伺服。它的权重是 0，内存是 MB 级，CPU 可跑。
6. **于是得到本轮假设。** 如果一条演示轨迹被表示在**任务相关的物体/受器坐标系**里，并且执行前用**多视角几何证书**验证它仍然适用于当前场景，那么它就能在位置、背景、干扰物、未见物品、人为干扰五个泛化轴上，补上 VLA 的最后 3 厘米；而且不需要第二个学习模型。

一句话：**上一轮缺的是「目标」，这一轮把目标做成「演示图式 + 多视角证书」。**

## 1. 先给结论：不是再训一个模型，而是把演示编译成可检索、可验证的接触图式

本轮的押注叫 **SCHEMA-WARP**：

> 把 33k 成功演示离线编译成 **DEMO-SCHEMA**：每个任务/阶段一条「物体相对轨迹 + 四视角关键帧 + 进入/退出条件 + 失败模式」。在线由 VLA 给出语义计划，选择阶段；从演示库检索最匹配的轨迹；用头双目/双腕估计当前物体/受器的**交互坐标系**；把演示轨迹 SE(3) 变换到当前场景；执行前用 **LITE-CERT** 做多视角重投影、可见性、深度一致性和间隙检查；通过后用 5 步 chunk + 视觉伺服执行；不通过就回退 VLA。

三个创新点，不是三个宏大名目：

1. **DEMO-SCHEMA（演示图式）**：把演示从「整条轨迹」拆成「阶段 × 交互坐标系 × 相对轨迹 × 多视角关键帧 × 前后条件」。它不是数据集格式，而是**运行时索引**；用 k-medoids 把 33k 条蒸馏到约 2k 条 exemplar，内存 <2GB。
2. **MV-WARP（多视角物体相对轨迹变换）**：不是回放绝对动作，而是 `T_W_EE*(t) = T_W_F(t) · T_F_EE^d(t)`；`F` 是杯架钩、网口、拉链滑块、锁孔、瓶盖、碗沿等任务相关坐标系。位置/背景/未见物品/人为干扰都变成「重新估计 `T_W_F`」。
3. **LITE-CERT（轻量多视角证书）**：执行前检查四视角重投影误差、深度一致性、可见性、IK/关节限位、与桌面/物体的间隙、检索 margin。它是**确定性几何检查**，不是第二个模型；拒绝错误演示，避免「检索到一条看似相似、实际会撞的轨迹」。

一个可选的、非主线的学习扩展是 **SCHEMA-ADAPTER**：在冻结 WLA 的 action head 旁加一个小 adapter，用检索到的演示关键帧做条件。它可能更强，但会触碰单模型/算力/数据泄漏风险，本轮只作为 stretch goal，不作为主押注。

三个灵感词怎么落地：

| 灵感词 | 落到哪里 | 明确不做什么 |
|---|---|---|
| **演示方案** | 演示图式（阶段/坐标系/相对轨迹/多视角关键帧/前后条件）；k-medoids 蒸馏；任务语言 5 个改写版本；检索 + 重打分 | 不把 33k 条整段视频硬塞进在线记忆；不做逐任务一个学习策略 |
| **轻量化设计** | 不新增学习模型；CPU 检索/几何/证书；<2GB 索引；5–8 步 chunk；可选 FastVLA/FastOPD/VLA-Rolling 只优化 VLA 侧 | 不再训 6B/14B；不做完整 sim-to-real 策略训练；不做第二个学习残差 |
| **多视角视觉** | 头双目恢复厘米级米制深度；双腕看接触细节；四视角重投影/可见性/深度一致性证书；对称物体多视角消歧 | 不把四路图简单拼成更多 token；不假设腕部内参缺失（已证伪）；不把头双目当毫米级深度 |

### 2.1 数据：32 任务、33,276 条、169.28 小时，四路 480×640 @30fps

32 个 HF 数据集逐项求和（2026-10-31 复核）：

| 项 | 数值 |
|---|---:|
| 任务数 | 32 |
| episodes | **33,276** |
| frames | **18,282,246** |
| 时长 | **169.28 h**（30 fps） |
| 单任务 episodes | 969–1,533 |
| 单任务平均时长 | 6.2 s（HangCup）–37.6 s（ToolboxStorage） |
| 视角 | 头双目 `head_stereo_left/right` + 双腕 `wrist_left/right`，均 480×640 |
| 语言 | 每任务 5 个改写版本，用 `@` 连接，例如 HangCup 的 5 句 |

完整任务列表、episodes/时长、接触原语分类见产物区 §1.3。这里只强调一个对方案最重要的事实：**任务不是 32 个互不相干的技能，而是 8 类接触原语的组合**——reach、grasp、lift、transport、align、insert/hook/place、fasten/turn/pour、release/retreat。比如 HangCup 是 `reach→grasp→lift→align→hook→release`；ZipUp 是 `reach→grasp→pull→release`；ToolboxStorage 是 `reach→grasp→transport→place` 多次 + `close/lock`。这给了 DEMO-SCHEMA 跨任务共享的基础。

### 2.2 修正：腕部相机有完整内参，缺的是手眼外参

上一轮写「腕部相机没有内参」是错的。`meta/info.json` 的 `camera_params` 里，HangCup 示例：

```text
wrist_left.color.camera_matrix  = [436.4058, 0, 323.9217; 0, 435.9215, 242.9332; 0, 0, 1]
wrist_left.color.dist_coeffs    = [-0.05146, 0.05475, -3.56e-5, 1.67e-4, -0.01769]
wrist_right.color.camera_matrix = [435.1151, 0, 319.0249; 0, 434.4995, 240.9933; 0, 0, 1]
```

这意味着：

- 腕部 **2D 像素 → 归一化射线** 可以直接做，不需要先标内参；
- 缺的是 `T_EE_cam`（腕相机相对 EE 的 6D 外参）。它可以用一次性手眼标定、已知标定板、或从演示中做自标定得到；
- 如果手眼外参暂时不可用，腕部仍可用于 **2D IBVS**（图像目标对齐），头双目负责 3D PBVS。方案不必因为外参未知而停摆。

这条修正把 G0 从「腕部能不能标内参」改成「腕部手眼外参能不能标到 ≤5px 重投影」，难度和风险都下降了一档。

但也不要因此把「头双目」神化：HangCup 的基线只有 58.25mm、焦距约 282px；在 0.5–1.0m 工作距离，0.5px 视差误差约对应 **7.6–30.4mm** 深度误差，要 3mm 需要 0.2px@0.5m 或 0.1px@0.6m，实际很难稳定。所以本轮的分工是：**头双目负责全局 3D/粗对齐/证书，毫米级接触靠腕部 2D + 演示轨迹 + 5 步伺服。** 这条对 G1 和 LITE-CERT 的阈值都是硬约束。

### 2.3 修正：WLA 只用了三路图，挑战赛给四路；右目是免费的几何信号

官方 WLA 的 `unitree.yaml` 有两个图像配置：

- `unitree_img_with_stereo`：`head_stereo_left` + `wrist_left` + `wrist_right`；
- `unitree_img_wo_stereo`：`head_stereo_left` + `wrist_left` + `wrist_right`（Dex1 默认用这个）。

也就是说，**官方 WLA 的 Dex1 训练/微调默认没有把 `head_stereo_right` 喂进 VLA**。挑战赛 API 的 `cam_left_high`/`cam_right_high` 却是成对的头双目。右目对 VLA 是额外输入，对几何层是**可直接三角化的米制深度**。这正好支撑「多视角视觉」不是再堆 token，而是拿来做几何验证。

### 2.4 修正：`action.pivot[7]` 是 API 的硬要求，WLA 54D 里没有这个槽

数据 README 明确：

```text
pivot [7] = vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height
```

HangCup 的 `stats.json` 里 `action.pivot` 的 mean 约为 `[0, 0, 0, 0, 0.15, 0, 0.738]`；`pivot_4` 和 `height` 近乎常数，中间三维的语义没有在公开文档里逐维定义。WLA 的 54 维动作有 waist/torso/base/legs，但没有一个叫 `pivot` 的 7 维槽。因此：

- 适配层必须显式构造 `action.pivot`；不能假设 WLA 的 54D 直接切片就能对上；
- 先用 `example_env.py`/单任务通道验证 `pivot` 的 7 维语义、范围和默认值；
- 保守回退是 **hold 当前下身/零 pivot**，只让双臂 + 夹爪动；这会限制 ToolboxStorage 等需要下身的任务，但能先跑通接口；
- 这条和「单模型合规」无关，是纯接口事实，必须在 P0 解决。

### 2.5 榜单：公开预览仍不可复核，本轮不依赖具体分数

2026-10-28 抓取时，官网首页/`leaderboard.html`/`runs.html` 显示「即将发布 Coming Soon」；2026-10-31 当前网络访问这些页面被 WAF 拦截，`leaderboard_data.json` 返回 HTTP 567 安全策略页，无法重新确认。上一轮状态文件里的 8 个模型分数（MolmoAct2 29.7% 等）**无法复核**，本轮不把它们当事实，只把「头部约 30%、尾差不到 10pp」当作一个待验证的难度信号（C 级）。本轮的方法不依赖某个模型的具体分数；它依赖的是官方数据、API、WLA 和公开论文。

### 2.6 公开论文给的信号：多视角演示有用，VLA 没用满多视角，立体/轻量是活跃方向

本轮检索到的、会改变方案的公开工作（具体引用见产物区 §11）：

- **Beyond Viewpoint Generalization（arXiv 2603.26757v3）**：受控实验显示多视角演示不仅提升跨视角鲁棒性，还提升单视角策略的成功率和泛化；多视角数据能突破单视角数据集的 scaling 上限；机制上是对齐了 action head 与视觉特征分布、减少过拟合。这直接支持「把多视角演示当作运行时资产」。
- **FocusVLA（arXiv 2610.31423v1）**：现有 VLA 没有充分利用多视角互补性，倾向于一直依赖腕部视角；stage-aware 动态 view routing 在 RoboTwin 2.0 上比 π0.5 高 10.10pp，真机 71.7%→85.0%。这支持「按阶段选择全局/局部视角」，而不是平均对待四路图。
- **ExStereo（arXiv 2610.04805v1）**：用显式立体表示把 2D VLA 提升到 3D，在 π0.5 和 SmolVLA 上一致涨点。这支持「头双目不是装饰，是精度来源」。
- **FastVLA（arXiv 2610.22146v2）**：任务条件 + 时间自适应的视觉 token 压缩，LLM backbone FLOPs 降 35–59%，动作延迟降 9–32%，成功率保持。**FastOPD（arXiv 2610.02832v1）**：on-policy 蒸馏到轻量学生，2 步推理保留 π0.5 84% 性能，延迟降 78.1%。**VLA-Rolling（arXiv 2610.25043v3）**：复用 action tail，最多 1.48× 加速，14/16 个 setting 涨点。这些是 VLA 侧的轻量化选项；本轮主线仍是不新增模型的运行时层，但它们可以作为「如果必须换小模型」的备选。
- **VersaCamVLA（arXiv 2610.12451v1）**：把可变相机集合映射到固定 scene token，部署时用轻量 spatial encoder 注入预训练 VLA。它证明「相机配置变化」可以被显式建模；我们的场景固定四路，但可以用它的思路做「四视角 → 统一交互坐标系」。
- **DreamZero（arXiv 2602.15922v1）**：14B world-action model，7Hz 实时闭环，跨 embodiment 迁移强；说明大模型/世界模型不是不行的，但 14B 的部署成本和 7Hz 的控制带宽，对最后 3 厘米仍不是最优解。
- **WALL-OSS-0.5（arXiv 2605.30877v2）**：4B VLA，预训练零样本可执行，15 个真机任务平均 60.5% **task progress**；注意 progress ≠ success，最后一步失败仍是 0 分。
- **DemoHLM（arXiv 2510.11258v1）**：从单条仿真演示到真实 G1 的可泛化 loco-manipulation，说明「演示 + 闭环视觉 + 分层」在人形机器人上是可行路线；我们的场景是桌面双臂、有 33k 真机演示，更适合做检索式图式。

## 3. 诊断：三个缺口，不是三个模型不够大

### 3.1 缺口一：演示只被压进权重，没有被当作运行时记忆

Behavior cloning 把 33k 条演示压缩进一组权重。权重学到的是「平均而言该怎么做」，但最后 3 厘米需要的是「这一个杯架钩、这一个网口、这一个拉链滑块，在这一条成功演示里是怎么对的」。这两件事不一样：

- 权重擅长语义和粗动作；
- 检索擅长 episode-specific 的接触几何；
- 两者不是替代关系，是分工。

如果只用 VLA，模型必须在每次推理时「回忆」某条演示的接触细节；如果只做检索，系统又不会理解任务。SCHEMA-WARP 把两者接起来：**VLA 决定做什么/到哪个阶段，演示记忆决定最后 3 厘米怎么走。**

### 3.2 缺口二：多视角只被当输入，没有被当验证

多视角有两个用途：

1. **感知**：头双目三角化、腕部看遮挡、局部高分辨率；
2. **验证**：同一条 3D 轨迹必须同时投影到四路图里，深度、可见性、尺度都要一致。

现有 VLA 主要用第 1 个；第 2 个几乎没被用。可是在单模型、无深度、无力的 API 下，验证比感知更便宜、更可靠：你不需要训练一个「失败检测器」，只需要检查几何是否自洽。

### 3.3 缺口三：最后 3 厘米没有被物体坐标系约束

绝对 EE 轨迹在位置/背景/人为干扰下会失效；相对某一帧的轨迹也可能失效（如果物体被移动/旋转）。正确的不变量是**任务相关的交互坐标系**：

- 挂杯：杯架钩的坐标系；
- 插网线：网口的坐标系；
- 拉拉链：拉链滑块的局部切向/法向；
- 开锁：锁孔的轴 + 钥匙转动轴；
- 倒药：瓶盖的轴；
- 叠碗：碗沿/碗心的坐标系。

把轨迹表示成 `T_F_EE(t)`，位置/背景/未见物品/人为干扰就变成「重新估计 `T_W_F`」。这就是「演示方案」真正的结构。

## 4. 方法：SCHEMA-WARP

### 4.1 总架构

```text
┌──────────────────────────────────────────────────────────────┐
│ Evaluator: N ports 8765..8765+N-1, 4 RGB, EE/gripper/lower_body│
└──────────────────────────────┬───────────────────────────────┘
                               │ obs / action chunk
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ Per-port PolicyService (CPU)                                 │
│  ├─ phase detector / task grammar                            │
│  ├─ DEMO-SCHEMA index (retrieval)                            │
│  ├─ multi-view frame estimator (head stereo + wrists)         │
│  ├─ MV-WARP (SE(3) trajectory transfer)                      │
│  ├─ LITE-CERT (reprojection/visibility/clearance/IK)         │
│  ├─ 5-step servo + action adapter (WLA 54D → API)            │
│  └─ fallback: VLA chunk / safe hold                          │
└──────────────────────────────┬───────────────────────────────┘
                               │ async, batched
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ Shared VLA server (GPU): UnifoLM-WLA-1.0, frozen/fine-tuned  │
│  - semantic task/phase plan                                  │
│  - fallback action chunk                                     │
└──────────────────────────────────────────────────────────────┘
```

- **唯一学习模型**：VLA。可以是官方 WLA Base，也可以只微调 action head。
- **确定性运行时层**：检索、几何、证书、状态机、伺服；无学习权重。
- **数据资产**：33k 演示蒸馏出的 DEMO-SCHEMA；是索引/数据库，不是第二个模型。
- **合规边界**：如果官方认为「检索索引」也算模型的一部分，我们把它归入「策略的数据文件」，并在提交材料中说明其无学习参数、只做最近邻/几何变换。

### 4.2 DEMO-SCHEMA：演示的运行时表示

每条 schema 记录一个「阶段实例」：

```json
{
  "schema_id": "HangCup/phase=hook/exemplar=03",
  "task_id": "G1_Dex1_HangCup",
  "task_aliases": ["Hang the cup ...", "...5 paraphrases..."],
  "phase": "hook",
  "phase_index": 4,
  "primitive": "insert_hook",
  "frame_type": "rack_hook",
  "T_W_F_keyframes": [[...], ...],
  "T_F_EE": [[x,y,z,qx,qy,qz,qw], ...],
  "gripper": [5.5, 5.5, 5.4, ...],
  "views": {
    "head_left":  {"keyframe_ids": [...], "descriptor": "..."},
    "head_right": {"keyframe_ids": [...], "descriptor": "..."},
    "wrist_left": {"keyframe_ids": [...], "descriptor": "..."},
    "wrist_right":{"keyframe_ids": [...], "descriptor": "..."}
  },
  "preconditions": ["cup grasped", "hook visible"],
  "postconditions": ["cup hanging", "gripper open"],
  "failure_modes": ["hook occluded", "cup slips", "collision with rack"],
  "source_episodes": [17, 42, 108],
  "quality": {"grasp_stability": 0.93, "contact_visibility": 0.88}
}
```

关键设计：

1. **阶段化**：不是一条整轨迹，而是 `reach/grasp/lift/transport/align/insert_hook/fasten/release` 的组合。阶段边界由夹爪开合、EE 速度、腕部光流/视觉变化检测；任务语言给出阶段顺序先验。
2. **物体相对**：存 `T_F_EE(t)`，不存绝对 `T_W_EE(t)`。`F` 是任务相关交互坐标系；对刚性物体用 6D 位姿，对铰接物体用「6D 位姿 + 关节参数」，对透明/反光物体用「局部 2D 特征 + 头双目深度」兜底。
3. **多视角**：每个阶段存 1–3 个关键帧 × 4 视角；头双目用于 3D，腕部用于接触细节。描述子优先用 ORB/颜色/几何不变量（无学习），可选冻结 VLA encoder（同 checkpoint，C3 合规）。
4. **前后条件**：不是装饰；它们是 LITE-CERT 和阶段状态机的输入。比如 `hook` 的 precondition 是「杯已夹稳、钩可见」，postcondition 是「杯挂在钩上、夹爪张开」。
5. **失败模式**：每条 schema 带失败模式，在线检测到就换 exemplar 或回退 VLA；这也是「演示方案」的一部分。

**蒸馏**：33k 条不需要全部在线。按任务 × 阶段 × 视角描述子做 k-medoids，每类保留 5–10 个 exemplar；32 任务 × 8 阶段 × 8 exemplar ≈ 2,048 条。每条存 4 视角 × 3 关键帧 × 128×128 JPEG + 30–60 步轨迹，估算 <2GB；在线常驻 <1GB。检索用 numpy/FAISS，CPU 单次 <5ms。

### 4.3 在线流程

```text
1. 读 obs（4 图、EE、夹爪、lower_body、language）。
2. VLA/任务语法给出 task + phase 先验；phase detector 用夹爪/EE/视觉事件推进。
3. 用 task + phase + 当前四视角描述子 + 当前 EE 位姿检索 top-k schema。
4. 对每个候选，估计当前交互坐标系 T_W_F(t)：
   - 头双目：特征/模板 → 三角化 → PnP/ICP；
   - 腕部：局部特征匹配 + 深度/尺度；
   - 对称物体：在对称群里选重投影最小的解；
   - 透明/反光：头双目 + 腕部 2D + 夹爪遮挡推理，置信度低则跳过。
5. MV-WARP：T_W_EE*(t) = T_W_F(t) · T_F_EE^d(t)；加起始对齐、时间缩放、关节/碰撞检查。
6. LITE-CERT：四视角重投影、深度一致性、可见性、IK/限位、间隙、检索 margin；全部过才执行。
7. 返回 5–8 步 EE chunk；块内 5 步视觉伺服；下一块重新估计/验证。
8. 若证书拒绝/进度停滞/人为干扰：回退 VLA chunk；必要时重新检索/重规划。
```

### 4.4 为什么是「物体相对轨迹」而不是「相对位姿目标」

CHUNK-SERVO 已经做了「检索一个目标相对位姿 `T_target_ee*`」。本轮再往前走一步：

- 一个目标位姿只告诉夹爪「最后停在哪」，不告诉它「怎么绕过杯沿/怎么让拉链头进入齿槽/怎么让网线卡扣先下压再推入」；
- 一条阶段轨迹包含**接近方向、插入轴、接触前后的微调、夹爪开合时序**；
- 轨迹在物体坐标系里，位置/背景/未见物品/人为干扰都只影响 `T_W_F`，不影响 `T_F_EE`；
- 轨迹可以被 LITE-CERT 逐点验证，而单个目标位姿只能验证终点。

所以本轮把「目标」从 6D 点升级为「6D 点 + 一条短轨迹 + 夹爪时序 + 前后条件」。

### 4.5 关键公式

**坐标变换**：

```text
T_W_EE*(t) = T_W_F(t) · T_F_EE^d(t)
```

如果演示存的是绝对轨迹：

```text
T_W_EE*(t) = T_W_F(t) · (T_W_F^d)^(-1) · T_W_EE^d(t)
```

**起始对齐**（避免第一帧跳变）：

```text
C = T_W_EE(t0) · (T_W_EE*(t0))^(-1)
T_cmd(t) = exp((1 - α(t)) · log(C)) · T_W_EE*(t)
α(t): 0 → 1，前 5–10 步线性/平滑过渡
```

**多视角重投影证书**：

```text
e_mv = Σ_v Σ_k ρ( || π_{K_v}(T_{C_v W} · x_k) - u_{v,k} ||_2 )
accept if e_mv < τ_f, visibility > τ_vis, clearance > d_safe, IK residual < τ_q
```

**检索打分**：

```text
s = w1·lang + w2·visual + w3·phase + w4·geometric + w5·smoothness
```

其中 `geometric` 用当前帧与候选 schema 的四视角重投影误差/尺度一致性，`smoothness` 用轨迹曲率/速度连续性。权重先用先验，单任务通道再校准。

### 4.6 轻量化设计：钱花在运行时，不花在第二个模型

- **不新增学习权重**：演示索引是数据库；检索是最近邻；warp 是 SE(3)；证书是几何；相位是状态机。
- **CPU 预算**：每端口检索 <5ms、几何/证书 <20ms、5 步 chunk 167ms；p99 目标 <50ms 额外延迟。
- **内存**：<1GB 常驻；<2GB 磁盘；多端口共享只读索引。
- **GPU**：只跑 VLA；如果 VLA 侧需要提速，可选 FastVLA token 压缩、FastOPD 蒸馏、VLA-Rolling tail reuse；这些是 VLA 的优化，不是第二个模型。
- **分辨率**：头图 240×320 做检索/深度，腕图 128×128 做接触；原图只在需要时取。
- **失败成本**：证书拒绝只损失一次 chunk，不会把机器人带进碰撞；回退 VLA 的代价可控。

### 4.7 与 CHUNK-SERVO / FACT-VLA / GEO-RESIDUAL 的关系

- **保留**：CHUNK-SERVO 的 5 步执行、相对目标、RTT/增益标定、单任务通道；FACT-VLA 的相位化；GEO-RESIDUAL 的动作条件残差/编辑检测。
- **升级**：从「检索一个相对位姿」升级为「检索一条阶段轨迹 + 图式 + 多视角证书」；从「头双目/腕部做伺服」升级为「四视角做几何验证」；从「任务级目标库」升级为「阶段级 schema 库」。
- **剪枝**：不做第二个学习模型；不做 6D 物体位姿网络；不做完整 sim-to-real 策略；不做 30Hz 广域网伺服；不把榜单当难度表。

|---|---|
| 观测图像 | `observation.images.cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640** |
| 本体 | `left_arm[7]`、`right_arm[7]`、`left_ee_pose_gripper_base[6]`、`right_ee_pose_gripper_base[6]`（xyz+rpy，base 系）、`left_gripper[1]`、`right_gripper[1]`、`lower_body[15]`、`language:str` |
| 动作空间 | `control_space` 仅 `"joint"` 或 `"ee"`，二者互斥 |
| 共享动作 | `action.left_gripper[1]`、`action.right_gripper[1]`、`action.pivot[7]` |
| EE 动作 | `action.left_ee_pose_gripper_base[6]`、`action.right_ee_pose_gripper_base[6]`（**绝对目标位姿**，xyz+rpy，base 系） |
| chunk | `action_chunk_size` 为正整数，固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action` |
| token | `metadata.token` 握手校验一次；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile**；API 也不直接给 `state_d435`/`state_torso` |
| 监控 | 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分 |

**关键推论**：

1. `action_chunk_size` 是控制参数，不只是推理参数。chunk=30 @30Hz = 1 秒开环；chunk=5 = 167ms。SCHEMA-WARP 的证书和伺服必须在 5–8 步的粒度上生效。
2. `control_space="ee"` 的动作是**绝对目标位姿**，不是相对增量；WLA 的 54D 是相对当前 EE 的 xyz+rotvec。适配层必须先 compose 成绝对位姿，再转 xyz+rpy。
3. `action.pivot[7]` 是 API 硬要求，但 WLA 54D 没有这个槽。数据 README 给出的定义是 `vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height`；中间三维语义未公开。P0 必须验证，保守回退是零 pivot/hold 下身。
4. 四路图里 `cam_left_high`/`cam_right_high` 对应头双目左右，`cam_left_wrist`/`cam_right_wrist` 对应双腕。头双目在数据中是 rectified；在线是否 rectified 需用 P0 示例确认，但同一机器人/同一数据管线大概率一致。
5. API 没有 `state_d435`/`state_torso`。在线头相机外参要么由 `lower_body` + 腰部/头部 FK 恢复，要么用标定物/固定安装先验；这是 G1 风险，不是可忽略项。

- **头双目 `T` 的单位是 mm**（-58.25 ≈ 58mm 基线）；**腕部 `extrinsics_to_color.translation` 的单位是 m**（约 0.018m）。同一份 metadata 里混了单位，代码必须显式换算。

- 腕部 `color.camera_matrix` 是完整内参，上一轮「腕部没有内参」的说法错误。缺的是 `T_EE_cam`（手眼外参）。
- 数据里有 `state_d435`（头相机在 base 系的 6D 位姿）和 `state_torso`，但**线上 API 没有**；在线头相机位姿要用 `lower_body[-3:]`（waist yaw/roll/pitch）+ 头部安装/FK 恢复，或在 reset 时用标定物。G1 必须验证。

### 1.5 官方基线：WLA 6B/2,500h/64 任务，但和挑战赛 API 有四个硬缺口（A）

`unifolm-wla` README / docs（2026-10-31 复核）：

| 项 | 事实 |
|---|---|
| 参数 | **6B** |
| 数据 | 约 **2,500 h** 真机数据 |
| 任务 | **64**（桌面 + 全身） |
| 统一动作 | **54D**；统一状态 **60D** |
| 默认 chunk | `chunk_size=30`、`target_fps=30`，覆盖约 `[0, 29/30]s` |
| 去噪 | 默认 **4 步** |

| Dex1 图像 | `unitree_img_wo_stereo` = `head_stereo_left` + `wrist_left` + `wrist_right`；**没有右目** |
| 动作语义 | EE 为相对当前 EE 的 xyz+rotvec；base/EE 相对位姿；其余模块按源数据语义 |
| 发布 | 2026-09-28 开源 Base 权重、微调代码、model server |

四个硬缺口：

1. **视图缺口**：WLA Dex1 只用 `head_left + 2 wrists`，挑战赛给 `head L/R + 2 wrists`。右目是免费的几何信号，但没进 VLA；这正好由 SCHEMA-WARP 的几何层使用。
2. **动作缺口**：WLA 54D 没有 `action.pivot[7]`；挑战赛 API 必须返回。需要显式映射/验证，不能假设切片对得上。
3. **位姿缺口**：WLA EE 是相对动作；挑战赛 EE 是绝对 base 系位姿。适配层要 `T_abs = T_current · T_rel`，再转 xyz+rpy。
4. **频率缺口**：WLA 默认 30 步；挑战赛 evaluator 的控制频率/执行节奏没有在 README 写死。chunk 5–8 是控制选择，不是模型默认。

**战略结论**：不要再从零训 6B；用 WLA Base 做语义/后备，把算力投到运行时图式层。WLA 是否已经覆盖挑战赛 32 任务、是否直接适配 API，必须先在单任务通道实测，不能假设。

## 2. 问题形式化

### 2.1 符号

| 符号 | 含义 |
|---|---|
| `T` | 32 个任务集合 |
| `E` | 33,276 条演示 episode |
| `o_t` | 当前观测：4 图、EE 位姿、夹爪、lower_body、language |
| `p` | 阶段（phase），来自 8 类接触原语 |
| `F` | 交互坐标系（interaction frame） |
| `T_W_F` | base/world 系到 `F` 的 SE(3) |
| `τ^d(s) = T_F_EE^d(s)` | 演示在 `F` 系下的 EE 轨迹，`s∈[0,1]` 为阶段进度 |
| `z = (k,p,F,τ^d,V,pre,post)` | 一条 DEMO-SCHEMA |
| `Z` | 蒸馏后的 schema 库，约 2k 条 |
| `π_VLA` | 唯一学习模型，给语义计划/后备动作 |
| `C(τ,o)` | LITE-CERT 证书，输出 accept/reject + 原因 |

### 2.2 目标

在单模型、无深度/力/触觉、远程 API、N 端口的约束下，最大化 32 任务平均成功率：

```text
max  E_{task~T, trial~10} [ success(task, trial) ]
s.t. 只有 π_VLA 一个学习模型；
     schema 索引是数据文件，不是第二个策略；
     每次 get_action 的 p99 额外延迟 ≤ 50ms；
     常驻内存 ≤ 1GB/端口共享索引；
     不引入力/触觉/深度传感器。
```

### 2.3 失败分解

把一次失败粗略分解为：

```text
p_fail ≈ 1 - (1-p_sem)(1-p_geom)(1-p_contact)(1-p_recovery)
```

- `p_sem`：选错任务/物体/顺序；VLA 的强项。
- `p_geom`：物体/受器位姿估计错、坐标系错、碰撞；SCHEMA-WARP 的几何层目标。
- `p_contact`：最后 3 厘米的插入/挂/拉链/拧/倒失败；演示轨迹 + 5 步伺服的目标。
- `p_recovery`：人为干扰/滑移/卡住后不能恢复；证书 + 重检索 + VLA 重规划的目标。

这不是严格概率模型，只用于工程分配：**把算力从「更大的 p_sem」转到「更小的 p_geom/p_contact/p_recovery」。**

### 2.4 为什么不是「再训一个策略」

- 单模型规则：第二个学习策略风险高。
- 数据：33k 条足够做检索，不足以保证从零训一个 6B 泛化到 32 任务 × 5 泛化轴。
- 算力：单张 24GB 只能微调 action head；从零训不现实。
- 可解释性：证书能告诉你「为什么拒绝」，学习残差不能。
- 边际收益：官方 WLA 已经把语义/规模做完；最后 3 厘米是检索/几何/控制的边际收益最高的地方。

```text
        ├─ 1. 读 parquet + 视频（按 episode 流式）
        ├─ 2. 相位分割（夹爪/EE/腕部光流/深度变化 + 任务语法）
        ├─ 3. 交互坐标系选择/估计（任务模板 + 多视角几何）
        ├─ 4. 物体相对轨迹 τ^d(s)（SE(3) waypoints + 夹爪时序）
        ├─ 5. 四视角关键帧 + 描述子
        ├─ 6. 前后条件/失败模式/质量分
        ├─ 7. k-medoids 蒸馏（每任务×阶段 5–10 个 exemplar）
        └─ 8. 索引：task/phase/frame/descriptor → schema
```

### 3.2 相位分割

#### 信号

- 夹爪开合：Dex1 范围 5.5（开）→ 0（闭）；归一化闭合度 `c(t) = (5.5 - g(t))/5.5`。
- EE 平移速度 `v(t) = ||p_EE(t) - p_EE(t-1)|| * fps`。
- EE 角速度 `ω(t) = ||log(R_EE(t-1)^T R_EE(t))|| * fps`。
- 腕部光流幅值 `f(t)`（局部接触/滑动）。
- 头双目深度变化/目标 ROI 位移。
- 任务语言给出的阶段顺序先验（例如 “open the zipper, place ..., close the zipper”）。

#### 事件

| 事件 | 触发条件（先验） | 用途 |
|---|---|---|
| `grasp` | `c(t)` 上穿 0.5，且 `v(t)` 低，且腕部 ROI 与物体重叠 | 进入 grasp 后 |
| `release` | `c(t)` 下穿 0.5 | 进入 release/retreat |
| `contact` | `v(t)` 局部极小 + `f(t)` 峰值 + EE 速度方向改变 | 进入接触段 |
| `insert` | contact 后 EE 沿一条近似直线低速推进，横向速度小 | 插入/挂/放 |
| `fasten` | EE 位置稳定但 `ω(t)` 持续 | 拉链/拧盖/开锁 |
| `pour` | EE 姿态翻转 + 目标容器 ROI 变化 | 倒药/倒水 |
| `retreat` | release 后 EE 远离目标 | 阶段结束 |

#### 分割算法

1. 对 `c,v,ω,f` 做 Savitzky–Golay 平滑（窗口 5–9 帧）。
2. 用滞回阈值检测事件；最小阶段长度 0.2s，避免抖动。
3. 用任务语法做动态规划对齐：阶段顺序固定/半固定，代价 = 事件时间偏差 + 阶段时长先验 + 缺失事件惩罚。
4. 输出阶段边界 `[t_start,t_end]` 和置信度；置信度低于阈值的 episode 不进 schema（或只进低质量池）。
5. 人工抽检 2% 做校准；不要全量人工标。

#### 8 类接触原语

| 原语 | 典型任务 | 关键帧 |
|---|---|---|
| `reach` | 所有 | 接近前 |
| `grasp` | 所有抓取 | 闭合瞬间 |
| `lift` | HangCup、StoreCups | 离桌 |
| `transport` | ToolboxStorage、OrganizeTools | 中段 |
| `align` | PlugInEthernet、PlugCharger | 预插入 |
| `insert/hook/place` | HangCup、ArrangeTestTubes、StackBowls | 接触/插入 |
| `fasten/turn/pour` | ZipUp、Unlock、PourOutMedicine | 旋转/拉动/倾倒 |
| `release/retreat` | 所有 | 张开/撤离 |

### 3.3 交互坐标系

#### 坐标系类型

| 类型 | 定义 | 例子 | 估计方式 |
|---|---|---|---|
| `target` | 受器/目标上的稳定坐标系 | 杯架钩、网口、试管孔、锁孔、瓶口、碗沿 | 头双目 + 模板/PnP；腕部局部验证 |
| `object` | 被操作物体上的坐标系 | 杯子把手、积木、手机、笔袋 | 头双目 + 物体检测/模板；腕部 |
| `tool` | 工具/夹爪上的坐标系 | 钥匙、注射器、球拍 | EE + 手眼/工具 CAD |
| `articulated` | 带关节参数的局部坐标系 | 拉链滑块、瓶盖、相框铰链、锁芯 | 6D 位姿 + 关节参数；多视角 |
| `deformable` | 局部材料坐标系 | 毛巾角、袋子边缘 | 局部 patch/光流；低置信度，P2/P3 |

#### 选择原则

1. **稳定性**：阶段内相对 EE 运动最小、可见性最高的坐标系。
2. **可观测性**：至少头双目或一个腕部能持续看到；否则降级。
3. **任务相关性**：挂杯选钩，不选杯；插网线选口，不选线；拉拉链选滑块，不选整袋。
4. **可验证性**：坐标系上的 3D 点能投影到多视角，且有足够特征。

#### 离线估计

- 对每个阶段，取 1–3 个关键帧；用头双目点云 + 目标 ROI 做 PnP/ICP；腕部做局部特征匹配。
- 如果目标有 CAD/模板：用模板点云/边缘；如果没有：用**参考演示帧**做模板（demo-relative），匹配 2D 特征 + 深度。
- 对每个坐标系，存 `T_W_F` 的关键帧、点云/特征、协方差；在线用同样的匹配。
- 对称物体：存对称群 `G`（如绕 z 轴每 90°）；在线在 `G` 上取重投影最小的解。
- 铰接物体：存 `T_W_F(q)` 的参数化；在线估计 `q`（拉链位置/瓶盖角/铰链角）。

#### 示例

| 任务 | 阶段 | 坐标系 | 轨迹要点 |
|---|---|---|---|
| HangCup | hook | 杯架钩 | 先抬到钩上方，再沿钩轴下压，最后松开 |
| PlugInEthernet | insert | 网口 | 先对齐轴线，再小幅下压卡扣，最后推入 |
| ZipUp | fasten | 拉链滑块 | 夹住滑块，沿齿槽切向拉，法向保持贴合 |
| Unlock | turn | 锁孔/钥匙轴 | 插入到底，再绕钥匙轴转 |
| StackBowls | place | 碗沿/碗心 | 对准碗心，下降，轻放，松开 |
| PourOutMedicine | pour | 瓶盖轴/容器口 | 拧盖，抬升，倾斜，倒，回正 |

### 3.4 多视角关键帧与描述子

#### 关键帧选择

- 阶段开始/结束；
- 夹爪闭合/张开瞬间；
- 接触/插入/旋转的极值帧；
- 腕部光流峰值/遮挡最严重帧；
- 目标 ROI 最大的帧。

每阶段 1–3 个关键帧 × 4 视角。

#### 描述子

优先无学习：

- ORB/SIFT 关键点 + 描述子；
- 颜色直方图（HSV，ROI）；
- 深度直方图/表面法向（头双目）；
- 几何不变量（三点夹角、距离比）；
- 夹爪开合/EE 相对位姿。

可选 C3 合规：

- 用**同一个 VLA checkpoint** 的视觉 encoder 特征；不加载第二个模型；
- 离线提取，在线只做最近邻；或在线共享 VLA 的 encoder 输出。

#### 索引

```text
key = (task_id, phase_id, frame_type)
value = [schema_id, descriptor, T_W_F_keyframes, T_F_EE, quality]
```

- 32 任务 × 8 阶段 × 8 exemplar ≈ 2,048 条；
- 每条 4 视角 × 3 关键帧 × 128×128 JPEG ≈ 0.6MB；
- 总计 <2GB；常驻 <1GB；
- 检索：先 task/phase 过滤，再 128–512 维描述子最近邻；numpy 暴力即可，<5ms。

### 3.6 演示蒸馏

- 对每个 `(task, phase)`，把所有候选轨迹按描述子/轨迹形状聚类；
- 用 k-medoids 选 5–10 个 exemplar，优先覆盖位置/背景/物体实例/语言改写；
- 质量分：阶段置信度、夹爪稳定度、接触可见性、轨迹平滑度、重投影误差；
- 去除离群/失败演示（如果数据里混有失败；官方称成功演示，但仍要做质量过滤）；
- 保留 `source_episodes` 便于追溯/审计。

### 3.7 数据划分与泄漏

- 按 **episode** 划分 train/val/test，不按帧随机划分；相邻帧不能跨 split。
- 如果元数据有场景/背景/物体 ID，按场景/物体分组；没有就用视觉聚类做 proxy。
- 语言改写：训练/验证时留出 1 个改写，测试语言鲁棒性；但 32 任务映射仍可预计算。
- 目标/受器实例：留出未见实例，测「未见物品」泛化。
- 证书阈值只能在 val 上选，不能在 test 上调。

## 4. 运行时：SCHEMA-WARP

### 4.1 架构

```text
obs ──► task/phase inference ──► retrieve top-k schema
                                      │
                                      ▼
                         estimate T_W_F (head stereo + wrists)
                                      │
                                      ▼
                         MV-WARP: T_W_EE*(t)=T_W_F·T_F_EE^d(t)
                                      │
                                      ▼
                         LITE-CERT (reprojection/visibility/
                         depth/clearance/IK/margin)
                           │ accept                 │ reject
                           ▼                        ▼
                 5-step servo chunk          VLA fallback / next schema
                           │                        │
                           └────────► action adapter (EE absolute, pivot) ──► evaluator
```

### 4.2 任务/阶段推断

- **任务**：32 类，语言改写 5 个/任务；用关键词/字符 n-gram/预计算 embedding 映射。在线不跑大文本模型。
- **阶段**：
  - 事件检测（§3.2）+ 任务语法状态机；
  - VLA 可选：让 VLA 输出阶段标签/进度，但解析失败不影响主流程；
  - 置信度 = 事件置信度 × 任务语法匹配 × 视觉/本体一致性；
  - 置信度低：不启用 warp，走 VLA。
- **阶段不是固定时间**：用进度 `s∈[0,1]`，由事件/距离/夹爪状态估计；warp 轨迹按 `s` 重采样。

### 4.3 检索

查询：

```text
q = [task_embedding, phase_onehot, visual_descriptor(4 views), EE_pose, gripper, T_W_F_prior]
```

打分：

```text
s(z) = w1·lang(z) + w2·visual(z) + w3·phase(z)
     + w4·geometric(z) + w5·smoothness(z) + w6·quality(z)
```

- `lang`：任务/阶段匹配（硬过滤优先）。
- `visual`：四视角描述子距离（ORB/颜色/深度）。
- `phase`：阶段一致；阶段不确定时给软权重。
- `geometric`：候选 `T_W_F` 投影到当前四视角的重投影误差/尺度一致性。
- `smoothness`：轨迹曲率/速度连续性。
- `quality`：schema 质量分。

先取 top-10，再用 `geometric` 重打分到 top-3；每个候选都过 LITE-CERT，取第一个通过且分数最高的。

### 4.4 交互坐标系估计

#### 头双目

1. 确认左右图 rectified；用 SGBM/BM 或稀疏特征匹配得到视差。
2. 目标 ROI：颜色/边缘/模板/ORB；不用学习分割（可选 C3 VLA 特征）。
3. 三角化 ROI 内的稀疏点/边缘点，得到相机系点云。
4. 与 schema 的 `F` 点云/模板做 PnP/ICP；或与参考演示点云做配准。
5. 输出 `T_C_F`，再用 `T_W_C` 转到 base 系。

#### 腕部

1. 用 `wrist.color.camera_matrix` 去畸变。
2. ORB/模板匹配到 schema 的腕部关键帧；得到 2D-2D 对应。
3. 用头双目深度/已知物体尺度把 2D 提升到 3D；PnP 得到 `T_C_F`。
4. 用手眼 `T_EE_C` 和当前 EE 位姿转到 base：`T_W_F = T_W_EE · T_EE_C · T_C_F`。
5. 手眼外参未知时，腕部只做 2D IBVS；3D 由头双目/参考演示给。

#### 多视角融合

- 每个视角给一个 `T_W_F` 候选 + 协方差；
- 用鲁棒位姿图/加权平均融合；Huber 降权离群视角；
- 对称物体：在对称群上取重投影最小解；
- 时间平滑：卡尔曼/滑动窗口，限制 `T_W_F` 的速度/加速度；
- 置信度：内点率 × 重投影误差 × 视角数 × 深度一致性。

#### 透明/反光/遮挡

- 透明/反光：边缘/背景/腕部 2D；降低置信度；证书更严；失败回退 VLA。
- 遮挡：用另一视角/参考演示；如果目标不可见，暂停 warp，先移动视角/回退。
- 变形：只对局部 patch 做 2D 对齐；不声称完整 6D。

### 4.5 MV-WARP

#### 基本变换

```text
T_W_EE*(s) = T_W_F(s) · T_F_EE^d(s)
```

如果 schema 存绝对演示：

```text
T_W_EE*(s) = T_W_F(s) · (T_W_F^d)^(-1) · T_W_EE^d(s)
```

#### 起始对齐

```text
C = T_W_EE(t0) · (T_W_EE*(s0))^(-1)
T_cmd(s) = exp((1 - α(s)) · log(C)) · T_W_EE*(s)
α(s): 0 → 1 over 5–10 steps
```

- 如果 `C` 太大（>5cm/10°），先执行一个短的 VLA/直线接近，再启用 warp；不要硬拉。
- 用 SE(3) 对数/指数插值，避免欧拉角跳变。

#### 时间缩放/进度

- schema 轨迹按 `s` 归一化；在线用事件/距离估计 `s(t)`。
- 如果当前进度落后：降速/等待；如果超前：保持/减速；不要跳过接触段。
- 可选 DTW：离线把多条演示按进度对齐；在线只用单调 `s`。

#### 夹爪时序

- 从 schema 取 `gripper(s)`；按当前 `s` 重采样；
- 夹爪命令在接触前保持开，接触时闭合，释放时开；
- 如果夹爪状态与 schema 不一致（滑移/没夹住），证书/恢复触发。

#### 运动学/碰撞

- 用 G1 URDF + 简化胶囊做 IK/自碰撞/桌面碰撞检查；
- 关节限位、速度/加速度限幅；
- 如果 IK 残差大/碰撞：拒绝该候选。

### 4.6 LITE-CERT

#### 检查项

| 检查 | 公式/做法 | 先验阈值 | 失败动作 |
|---|---|---|---|
| 重投影 | `e_rep = Σ_v Σ_k ρ(||π_v(T_C_W x_k)-u_{v,k}||)` | ≤3px 或 2σ_cal | 下一个候选 |
| 深度一致 | `|Z_proj - Z_stereo|` | ≤3σ_Z（见 §5.1） | 下一个候选 |
| 可见性 | 接触段至少 1 头 + 1 腕可见的比例 | ≥0.7 | 下一个候选 |
| 间隙 | EE/夹爪胶囊到点云的最小距离 | ≥5mm | 拒绝 |
| IK | 关节残差/限位 | ≤5mm/0.02rad | 拒绝 |
| 检索 margin | `d2 - d1` | ≥τ_margin | 拒绝/下一候选 |
| 平滑 | 最大速度/加速度/ jerk | 先验限幅 | 拒绝 |
| 可达 | 单 chunk 位移 | ≤2cm/5° | 降速/分段 |

#### 证书输出

```json
{
  "accept": true,
  "schema_id": "HangCup/phase=hook/exemplar=03",
  "score": 0.87,
  "checks": {
    "reprojection_px": 1.9,
    "depth_mm": 8.4,
    "visibility": 0.82,
    "clearance_mm": 14.2,
    "ik_residual_mm": 2.1,
    "margin": 0.11
  },
  "reasons": []
}
```

- 证书是确定性的；同样的输入给同样的输出。
- 记录所有 reject 原因，离线统计 false accept/reject；阈值只在 val 上调。
- 证书不是「安全认证」，只是「几何自洽 + 间隙 + 可达」的必要条件；不替代急停/限幅。

### 4.7 执行与动作适配

#### chunk

- 建议 `action_chunk_size = 5` 或 `8`；先扫 3/5/8，选 p99 与成功率折中。
- 30Hz 下 5 步 = 167ms；8 步 = 267ms。
- 块内用 5 步伺服（CHUNK-SERVO）：IBVS/PBVS 修正到 warp 轨迹的当前 waypoint。
- 下一块重新估计 `T_W_F`、重新检索/验证；不要把一个 30 步计划盲执行到底。

#### EE 绝对位姿

```text
T_abs_k = T_current_EE · T_rel_k          # WLA 相对动作 → 绝对
xyz, rpy = decompose(T_abs_k)             # API 要 xyz+rpy
```

- 注意 WLA 的 relative 是「相对当前 EE 局部系」；挑战赛是 base 系绝对位姿；不能直接相加欧拉角。
- 用旋转矩阵/四元数 compose，再转 rpy；避免 gimbal/顺序错误。
- `action.left/right_ee_pose_gripper_base` 都是 base 系，左右臂不要镜像坐标系。

#### pivot

- 数据 README：`pivot = [vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]`。
- 最可能的映射（C 级，待验证）：`vx,vy,angle_z,height` 来自 WLA base_command；`pivot_3/4/5` 对应 waist yaw/roll/pitch。HangCup stats 中 `pivot_4≈0.15`、`height≈0.738` 近乎常数，支持「腰部/高度保持」的解释，但不足以定论。
- P0 验证：用 `example_env.py` + 单任务通道，打印 pivot 的 7 维，试零/保持/映射三种；观察机器人是否动、是否报错。
- 保守回退：零 pivot/hold 当前下身；先让双臂任务跑通。

#### 夹爪

- Dex1：5.5（开）→ 0（闭）；确认 API 的夹爪命令范围/方向与数据一致。
- 归一化/裁剪；不要假设 0/1 二值。

### 4.8 恢复

```text
if cert_reject or progress_stall or edit_detected:
    hold position
    re-localize T_W_F (head stereo + wrists)
    if target visible:
        re-retrieve / re-warp with conservative gains
    else:
        ask VLA to re-plan with new image + language
    if retries > max:
        fail gracefully / safe retreat
```

- `edit_detected`：GEO-RESIDUAL 的动作条件残差；人或环境移动了物体。
- `progress_stall`：`s(t)` 在 N 步内不增，或 EE 跟踪误差大。
- `slip`：夹爪闭合但物体相对 EE 位移（腕部视觉/夹爪状态）。
- 每次恢复最多 2–3 次；之后回退 VLA 或安全停。

### 4.9 伪代码

```python
class SchemaWarpPolicy:
    def __init__(self, vla, schema_index, calib):
        self.vla = vla
        self.index = schema_index
        self.calib = calib
        self.phase = PhaseMachine()
        self.last_cmd = None

    def get_action(self, obs):
        task = infer_task(obs.language)
        phase, s, conf = self.phase.update(obs, task)

        if conf < TH_PHASE or phase in ("reach", "transport"):
            return self.vla_chunk(obs)

        candidates = self.index.search(task, phase, obs, topk=10)
        candidates = rerank_geometric(candidates, obs, self.calib)

        for z in candidates[:3]:
            T_W_F = estimate_frame(z, obs, self.calib)
            if T_W_F is None:
                continue
            traj = warp(z, T_W_F, obs, self.phase.progress)
            cert = lite_cert(traj, z, obs, self.calib)
            if cert.accept:
                self.last_cmd = traj
                return make_chunk(traj, obs, chunk_size=5)

        return self.vla_chunk(obs)   # fallback

    def vla_chunk(self, obs):
        return self.vla.get_action(obs)  # WLA 54D → API EE/pivot/gripper
```

## 5. 多视角几何

### 5.1 头双目深度精度：不是“毫米级”，是厘米级

头双目基线 `b≈58–61mm`，焦距 `f≈228–282px`（按任务不同）。视差 `d = f b / Z`，深度误差：

```text
σ_Z ≈ (Z^2 / (f b)) · σ_d
```

以 HangCup 的 `f=282px, b=58.25mm` 为例：

| 距离 Z | 视差 d | σ_Z @0.5px | σ_Z @0.2px | σ_Z @0.1px |
|---:|---:|---:|---:|---:|
| 0.3m | 54.8px | 2.7mm | 1.1mm | 0.5mm |
| 0.4m | 41.1px | 4.9mm | 1.9mm | 1.0mm |
| 0.5m | 32.9px | 7.6mm | 3.0mm | 1.5mm |
| 0.6m | 27.4px | 11.0mm | 4.4mm | 2.2mm |
| 0.8m | 20.5px | 19.5mm | 7.8mm | 3.9mm |
| 1.0m | 16.4px | 30.4mm | 12.2mm | 6.1mm |

结论：

- 头双目在桌面工作距离（0.5–1.0m）的 0.5px 匹配误差约 **8–30mm**；要 3mm 需要 0.2px@0.5m 或 0.1px@0.6m，实际很难稳定。
- 所以：**头双目负责全局 3D/粗对齐/证书，毫米级插入靠腕部 2D + 伺服 + 演示轨迹**。不要把「有双目」误当成「有毫米级深度」。
- 深度误差也决定了 LITE-CERT 的 `τ_z`：按当前距离/视差置信度自适应，而不是固定 2mm。

### 5.2 腕部内参与手眼

- 腕部 `color.camera_matrix` 已有；去畸变用 `inverse_brown_conrady`。
- 缺 `T_EE_cam`；标定方法：
  1. 棋盘格/ArUco 固定在夹爪上，移动多个位姿，解 `AX=XB`；
  2. 用数据中 EE 位姿 + 腕部图像，做自标定（重投影最小化）；
  3. 用已知物体尺寸 + 头双目深度，做一次性尺度/外参拟合。
- 标定目标：重投影 ≤5px；如果达不到，腕部只做 2D IBVS。
- 腕部是单目彩色，没有立体；3D 依赖头双目/已知尺度/参考演示。

### 5.3 多视角重投影与可见性

- 对每个候选轨迹 waypoint，投影 EE/夹爪上的 3–5 个 3D 点；
- 在四视角中找可见点（ROI 内、深度在前、不在遮挡后）；
- 加权重投影误差：头双目权重高（全局），腕部权重高（接触段）；
- 可见性 <0.7 时拒绝或换候选；
- 对透明/反光物体，用边缘/背景特征，降低权重。

### 5.4 对称与铰接

- 对称：`T_W_F` 有多个等价解；在对称群 `G` 上枚举/优化，选重投影最小且轨迹间隙最大的解；多视角消歧。
- 铰接：`T_W_F(q)`；在线估计 `q`（拉链位置、瓶盖角、铰链角）；轨迹随 `q` 变化；证书检查 `q` 的单调性/范围。
- 变形：局部 patch 坐标系；2D 对齐；不声称完整 6D；P2/P3。

### 5.5 失败检测

- 重投影/深度/可见性突然变差；
- `s(t)` 停滞；
- 夹爪闭合但物体相对 EE 移动（腕部视觉）；
- EE 跟踪误差/IK 残差大；
- 人为干扰：动作条件残差（GEO-RESIDUAL）；
- 触发恢复，不硬执行。

## 6. 轻量化设计

### 6.1 延迟预算（单次 get_action，CPU）

| 步骤 | 预算 |
|---|---:|
| 图像解码/缩放 | 5ms |
| 任务/阶段 | 1ms |
| 检索 top-10 | 3ms |
| 交互坐标系估计（ORB/PnP，2–3 视角） | 10–20ms |
| MV-WARP | 1ms |
| LITE-CERT | 5–10ms |
| 5 步伺服/动作适配 | 2ms |
| **合计** | **27–42ms** |
| 目标 p99 | **≤50ms** |

VLA 推理 100–300ms 在后台以 1Hz 运行；5 步 chunk 167ms；端到端约 200–350ms（含 RTT）。如果 RTT 高，chunk 3–5；如果 RTT 低，chunk 5–8。

### 6.2 内存/存储

| 项 | 估算 |
|---|---:|
| schema 索引（2k 条，4 视角 × 3 关键帧 128×128 JPEG） | <2GB 磁盘 |
| 在线常驻（描述子/轨迹/索引） | <1GB |
| 每端口状态 | <50MB |
| 全量 33k 关键帧（不推荐在线） | 10–20GB |
| 视频全量 | 数 TB；只流式/按需 |

### 6.3 多端口部署

- schema 索引只读，多端口共享；每端口独立 `PhaseMachine`/`last_cmd`/`reset`；
- 无 GPU 竞争：几何层全 CPU；VLA 共享 GPU server，批处理/异步；
- 端口从 8765 起连续 N 个；每个端口独立 token/状态；
- 内存不随 episode 增长：每个 episode reset 清空状态，索引不重载。

### 6.4 与其他轻量化路线对比

| 路线 | 学习参数 | 数据需求 | 延迟 | 风险 | 本轮定位 |
|---|---:|---:|---:|---|---|
| 从零训 6B/14B | 6B/14B | 大规模 | 高 | 算力/数据/单模型 | 不做 |
| 全量微调 WLA | 6B | 32 任务 | 高 | 过拟合/算力 | 只微调 action head（可选） |
| 蒸馏小 VLA（FastOPD） | 小 | 教师数据 | 低 | 性能损失 | VLA 侧备选 |
| 学习 adapter（SCHEMA-ADAPTER） | 10–100M | 33k | 中 | 单模型解释/泄漏 | stretch goal |
| **SCHEMA-WARP（本轮）** | **0** | **33k 演示索引** | **低** | 几何/检索失败 | **主线** |

### 6.5 VLA 侧可选优化

- FastVLA：token 压缩，降 35–59% FLOPs/9–32% 延迟；
- FastOPD：2 步蒸馏，保留 84% 性能，延迟降 78.1%；
- VLA-Rolling：action tail 复用，最多 1.48× 加速；
- 这些不改变「单模型」前提；但本轮主线不依赖它们，避免把工程绑在未验证的加速上。

## 7. 实验设计

### 7.1 离线

**划分**：按 episode 80/20；按场景/物体/背景分组；语言留 1 个改写；相邻帧不跨 split。

**指标**：

- 检索 top-1/top-5 是否含几何有效 schema；
- 交互坐标系误差（mm/°）；
- warp 轨迹终点/中间 waypoint 误差；
- 证书 precision/recall/false accept；
- 延迟（p50/p99）、内存。

**基线**：

- 任务级最近邻（不区分阶段）；
- 绝对轨迹回放；
- 单视角（head-only / wrist-only）；
- 无证书；
- 随机 schema（负对照）。

### 7.2 仿真

**平台**：MuJoCo/IsaacLab + G1 URDF + Dex1；官方 `unitree_sim_isaaclab`/`unitree_mujoco` 可用。

**任务族**（5 个）：

1. HangCup（hook）；
2. PlugInEthernet（insert）；
3. StackBowls（stack）；
4. ZipUp（fasten/pull）；
5. PourOutMedicine（unscrew/pour）。

**扰动**：

- 物体位置 ±10cm / ±15°；
- 背景纹理/光照；
- 0–3 个干扰物；
- 未见物体实例（同类别不同几何/颜色）；
- 人在 t 时刻移动目标（±10cm）；
- 延迟 0/50/100/150ms；
- 相机外参小扰动（±2mm/±0.5°）。

**对比**：

- VLA-only；
- schema-warp-only；
- VLA + warp；
- VLA + warp + cert；
- head-only / wrist-only / 4 views；
- absolute vs object-relative；
- task-level vs phase-level。

**指标**：成功率、步骤分、碰撞/超时、恢复率、p99。

**样本量**：每条件 100 次仿真；报告 95% CI；不要用 10 次仿真下结论。

### 7.3 真机单任务 A/B

**任务**：HangCup、PlugInEthernet、StackBowls、ZipUp、PourOutMedicine；再加一个非接触控制（FoldTowel 或 FruitCollection）防回归。

**协议**：

- 单任务不计分通道；
- 每任务 5 次 warp off / 5 次 warp on，配对初始条件；
- 同一机器人/同一校准；记录成功、步骤分、时间、p99、人工干预；
- 通过：≥3/5 任务 +10pp；非接触任务不回归 >5pp；
- 不通过：不烧正式提交。

**统计**：paired bootstrap 10k；报告 95% CI；10 trials/task 的方差很大，只对大幅效应下结论。

### 7.4 32×10 干跑

- N 端口从 8765 起；每端口独立 reset；
- 32 任务 × 10 次 dry run（可用 stub/仿真回放，不一定要真机）；
- 检查端口串扰、内存增长、p99、timeout；
- 通过后才提交。

- **第一批（P1，5 个代表）**：HangCup、PlugInEthernet、StackBowls、ZipUp、PourOutMedicine。

### 8.2 单任务通道协议

1. 选 5 个 P1 代表 + 1 个非接触控制。
2. 每任务 5 次 off/5 次 on；配对初始条件；同一校准。
3. 记录成功、步骤分、时间、p99、干预、碰撞。
4. 通过标准：≥3/5 +10pp；控制不回归 >5pp；p99 ≤50ms。
5. 扫 chunk 3/5/8；扫证书阈值；选稳定域，不选单点最高。
6. 通过后再做 32×10 干跑。

### 8.3 提交节奏

- 若允许多次提交：先交安全基线（WLA + API adapter + chunk 8/30），锁更早提交 tie-break；再交 SCHEMA-WARP。
- 若只允许一次：单任务通道打磨到稳定，再交最终版。
- 不要在正式评测里做超参搜索；所有阈值在离线/单任务通道定好。
- 保留回滚开关：证书连续拒绝/延迟超限时自动回退 VLA。

### 8.4 明确不做

- 从零训 VLA/World Model；
- 完整 sim-to-real 策略训练；
- 第二个学习模型/残差策略；
- 6D 物体位姿网络；
- 力/触觉闭环（API 没有）；
- 30Hz 广域网伺服；
- 32 个任务各训一个策略；
- 把未复核榜单当难度表；
- 在正式评测里调阈值。

### 9.3 安全

- 所有轨迹限速/限幅；单 chunk 位移 ≤2cm/5°；
- 碰撞/IK 失败立即停；
- 证书拒绝不执行；
- 恢复最多 2–3 次；
- 不依赖力/触觉（没有）；用视觉/本体/夹爪状态兜底；
- 不把证书当安全认证；保留硬件急停/人工干预。
