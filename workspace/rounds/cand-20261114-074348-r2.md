# 第 70 轮（承接第 69 轮「FLUID-RAS 交互消歧闭环」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「传感器标定」×「需求洞察」）

> R69 学会了向外求证：看不清就看、拿不准就问、质感不明就摸。但它仍默认两件事：**（i）优化的目标（需求 ν）是已知的，不确定的只是「怎么做」；（ii）标定层的职责是把传感器残差压到最小。** 这两个默认在桌面操作、家庭服务、康复辅助等真实场景里会同时崩塌。
>
> 第一，**R69 的 VoI 是相对「动作模态 M」算的，不是相对「需求 ν」算的**。如果用户说「帮我收拾一下」，系统可以把「先拿杯子还是先拿盘子」消歧到 99% 置信，却完全不知道「收拾」在她的语境里是「把药收进抽屉、别动桌上的文件」。**把错误的题做得越精确，错得越彻底。** 需求洞察不是又一个待消歧的模态，而是决定「什么算好」的那一层。
>
> 第二，**标定误差不是内禀地坏，它只在被需求放大时才坏**。同一个 5mm 外参误差，对推箱子无所谓，对轴孔装配是灾难；R68/R69 却用统一的 r_res / Δa 去评估它，于是把预算花在「与当前需求无关的精度」上。更阴险的是**双向吸收**：
> - **需求被标定吸收**：用户稳定的「轻一点」偏好，在力传感器上表现为一个系统性偏置，被 COF 当成漂移标定掉——系统于是「证明」用户没有这个需求；
> - **漂移被需求吸收**：力传感器真的漂了，行为模型却把它解释成「用户最近喜欢更用力」——系统于是「洞察」出一个不存在的需求。
>
> 这两个吸收是同一个病：**观测里 θ（标定）与 ν（需求）共线，被动数据无法分辨是谁在说话。** 这是一个**可辨识性（秩）问题**，不是估计精度问题；估计器再好，秩亏就永远分不开。
>
> 核心命题：**把「需求」与「标定」作为一对互相混淆的潜变量联合估计；只关心投影到当前需求上的那部分标定不确定性；用一份统一的实验预算，在「问/看/示范」（洞察需求）与「触碰已知参照/激励轨迹」（标定传感器）之间，优先选择能「打断混淆、增加可辨识秩」的实验；当预算内无法辨识时，不强行归因，而是对需求后验做鲁棒对冲（CVaR/maximin），再退化为 R69/R68。需求已知且标定已观测时，逐指令退化为 FLUID-RAS。** 命名 **DIAL-RAS**（Disentangling Intent And caLibration）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**我看到的这个『需要』，是真的需求，还是我坏掉的传感器在替用户说话？——而这张桌子、这个参照物，能不能帮我把它俩分开？**」

## 0. 直觉与动机

**灵感 1（传感器标定 → 精度是相对的，可辨识性是有方向的，参照物是主动证据）**
直觉：校准一个传感器，从来不是「把它调到绝对正确」，而是「相对一个已知参照，把误差压到当前用途可接受」。这带来三个被前几轮忽略的结构：
(a) **标定只在被激励的方向上有效**——你不动那个自由度，就永远不知道它准不准（R68 的缓变故障正活在此处，R69 的 FMA 也只是「怀疑」而非「辨识」）；
(b) **标定需要一个与待测量独立的参照**（砝码、支撑平面、标记点、重力方向），没有独立参照的「自校准」会把偏差解释成别的东西；
(c) **标定的价值取决于用途**——为 1mm 装配标定 5μm 是浪费，为推箱子标定 5μm 同样是浪费。把 (a)(b)(c) 合起来：**标定是一个有方向、有参照、有需求权重的实验设计问题，而不是残差最小化问题。**

**灵感 2（需求洞察 → 需求是被「揭示」的，不是被「声明」的；行为比话更可信，但行为会被坏传感器污染）**
直觉：真正的需求洞察很少来自用户直接说「我的效用函数是……」，而来自**揭示性证据**：用户在两个方案间选了哪个、在哪一步犹豫/皱眉/纠正、哪些东西被反复拿起又放下、什么情况下说「就这样吧」。这与逆强化学习/偏好学习同源：从选择与纠正反推 ν。但需求洞察有两个 R69 没有的难点：
(a) **陈述–行为偏差**：用户说的偏好（stated）与做的选择（revealed）常常不一致，系统必须学会「以行为为主、以陈述为约束」，而不是简单取平均；
(b) **行为证据的可信度依赖标定**：如果力传感器偏了，「用户选了轻拿」这条证据本身就被污染。**不校准就洞察需求，等于用一把坏尺子量用户的偏好。** 反之，标定也需要知道「哪些自由度对当前需求重要」，否则会把预算花在无关精度上。

**灵感 3（相互混淆 → 这是一个加秩问题，不是一个滤波问题）**
直觉：θ 与 ν 都通过观测说话。若在数据流形上两者的雅可比列空间重合（例如「力偏置 +5N」与「偏好更轻」产生同一组力读数与同一种纠正行为），那么无论估得多准，**都无法分辨是哪一种**——这是秩亏，不是噪声。R68/R69 的所有残差/似然检验在这个退化流形上都会失效：
- R68 的 r_res 在「需求被标定吸收」时 ≈0；
- R69 的 Δa 在「漂移被需求吸收」时也可能 ≈0，因为策略确实在「按用户当前表现出的偏好」高似然地生成动作。
因此核心工具不是更好的估计器，而是**主动加秩**：选一个实验，使 `[∂y/∂θ | ∂z/∂ν]` 的秩增加。最天然的加秩实验就是**已知参照实验**：让系统触碰/放置在一个几何已知的参照上，此时 θ 获得了不受 ν 影响的直接观测；或让用户在**两个都满足当前 θ 假设、但只有在不同 ν 下才会被偏好**的方案间做选择，此时 ν 获得了不受 θ 影响的直接观测。**参照物负责标定，选择负责洞察，二者共同打断混淆。**

**灵感 4（需求不确定性 → 不能只「收紧」，还要「对冲」）**
直觉：R68/R69 对不确定性的答案都是收紧（λ_floor）。但当不确定的是**目标本身**时，收紧是错的：把速度降到 0 不能解决「你要我把药收进抽屉还是别动」这个问题。正确姿势是对需求后验做**鲁棒对冲**——选一个在多个高概率需求下都不坏的动作（CVaR/maximin），而不是对某个猜测的需求「精确但脆弱」地优化。这给 DIAL 增加了独立于 R69 的安全层：**先对冲需求，再收紧动作。** 当需求后验退化到单点时，这一层自动消失，回到 FLUID/R68。

**灵感 5（新攻击面 → 需求是可被「喂养」的）**
直觉：一旦系统会从行为推断需求，就有人会**表演行为**来操纵它：故意表现得很急以获得更快的策略，故意轻放以获得更保守的抓取，甚至用假纠正把系统推到某个期望的效用。需求洞察因此是一门**被操纵的偏好学习**。再加上标定投毒（伪造参照、污染激励轨迹），DIAL 的威胁模型必须同时覆盖「骗它的尺子」和「骗它的心」。

## 1. 形式化定义（增量：定义 310–326）

**定义 310（DIAL-RAS 总览）** DIAL-RAS = (NIM, JCB, NEP, CDX, VoE, NRS, RAS-WM†)。三不变式：
(i) **实时流零学习写操作**（继承 R68 定义 276-i）；
(ii) **统一实验预算硬约束**：任务动作、信息动作、标定动作共享同一份时间/位移/社交成本预算，且三者都必须通过 C-RAS-WM 认证；
(iii) **可辨识性纪律**：不得在混淆指数越界且未做解耦实验时强行归因（不把不确定的「传感器 vs 需求」判定写进证书）；无法在预算内加秩时，进入需求鲁棒保守（NRS），而非编造归因。

**定义 311（潜在需求模型）** 需求 ν ∈ 𝒩 ⊆ ℝ^{d_ν} 是效用参数。给定可观测结果特征 φ(ξ, y) ∈ ℝ^{d_φ}，效用 U_ν(ξ) = νᵀφ(ξ, y)。需求证据分两类：**陈述证据**（用户显式说明/回答问题）与**揭示证据**（选择、纠正、放弃、停留、重复）。需求后验 b(ν) = p(ν | 𝒟_t) 不被假设为单峰；用其决策边际 ΔU = U_{ν}(ξ₁*) − U_{ν}(ξ₂*) 度量「需求是否真的影响决策」，而非仅用熵。

**定义 312（联合标定–需求状态 JCB）** x = (θ, ν)，联合信念 b_t(x) = p(θ, ν | 𝒟_t)，**不假设 θ ⊥ ν**。记录交叉协方差 Σ_{θν} 与混淆指数。θ ∈ Θ 为标定参数（外参、零偏、尺度、时延、力/力矩零点）。

**定义 313（传感–行为观测模型）** 传感器模型 y ~ p(y | ξ, θ)；行为/反馈模型 z ~ p(z | ξ, y, ν)（用户对结果的评价、纠正动作、二选一、犹豫时长）。**两者的关键区别**：y 直接依赖 θ 而不依赖 ν，z 直接依赖 ν 而不依赖 θ（但通过 y 间接耦合）。这一结构差异是解耦实验的物理基础。

**定义 314（需求–标定混淆指数 CDX）** κ = I(θ; ν | 𝒟_t) / min(H(θ), H(ν)) ∈ [0,1]；线性高斯下有闭式：κ = ρ_max(Σ_{θν})，ρ_max 为矩阵白化后的最大奇异值（典型相关）。κ→1 表示在当前数据流形上 θ 与 ν 不可分；κ 的变化率 \dot κ 用于在线探测「刚刚发生的吸收」。

**定义 315（需求相关校准子空间 NEP）** 决策损失 L(ξ, ν, θ)。在当前需求后验下的校准敏感度 J_ν(θ) = ∂/∂θ E_{ξ~π, ν~b}[L(ξ, ν, θ)]。定义**需求投影校准不确定性**
U_cal^ν = tr(J_ν Σ_θ J_νᵀ)（LQG 近似）或 max_{θ∈credible} [L(ξ*; ν, θ) − L(ξ*; ν, θ̂)]（分布鲁棒版）。
与 J_ν 零空间正交的 θ 方向记为**需求无关方向**，其不确定性不计入预算优先级——这是「只修会被当前需求放大的误差」的形式化。

**定义 316（标定动作与可激励性）** 标定动作 𝒜_cal = {known-ref touch, excitation trajectory, hold-pose(重力), fiducial re-observe, ask-user-to-place-on-target}。每个动作 c 产生设计矩阵 Φ_c；一组动作 𝒯 的经验 Fisher 信息 F(𝒯) = Σ_c Φ_cᵀ Φ_c / σ²。零特征值方向**不可辨识**（未被激励）。需求感知激励设计：
c* = argmin_c tr(J_ν (F(𝒯∪{c}) + I_prior)^{-1} J_νᵀ)，s.t. 安全与预算。
即：不是「最大化总信息」，而是「最大化对当前需求重要的那部分信息的秩与量」。

**定义 317（统一实验动作与预算）** 增广实验动作 e = (a, g, c) ∈ 𝒜_{++} = 𝒜_task × 𝒜_info × 𝒜_cal。共享预算 B：单位时间满足 τ_task + τ_info + τ_cal ≤ B_t，物理位移 ≤ ε_g+ε_c，社交打扰 ≤ c_max。任何 e 必须整体通过 C-RAS-WM 前缀认证（继承 R69 定义 293-ii、302）。

**定义 318（实验价值 VoE）** 设实验前的期望决策损失为 L̂₀ = min_ξ E_{x~b_t}[L(ξ, x)]。对实验 e，令 𝒟_e 为其可能观测：
VoE(e) = L̂₀ − E_{𝒟_e}[ min_ξ E_{x~b(·|𝒟_e)} L(ξ, x) ] − cost(e)。
VoE 可分解为 **VoN**（降低需求不确定性带来的损失下降）、**VoCal**（降低 θ 不确定性带来的损失下降）与 **VoD**（降低 θ–ν 混淆带来的损失下降）；三者一般不可简单相加，统一由后验预测损失计算。选择 e* = argmax VoE(e)，s.t. 安全、可激励性与预算；若 VoE(e*) ≤ 0 则不实验。

**定义 319（需求洞察算子 NIM）** 后验更新
b(ν) ∝ b(ν) · Π_i [ p(z_i | ξ_i, y_i, ν) ]^{w_i} · p(stated | ν)，
其中证据可信度 w_i = g(U_cal^ν_i, calib_freshness_i) ∈ [0,1]：**标定越不可信，揭示证据权重越低**（坏尺子量出的行为不可信）；陈述证据以操纵模型 p(stated | ν, manip) 进入，并设上限权重 w_stated ≤ w_max，避免「用户说什么就是什么」。沿用 R69 证据纪律：关键需求更新需（陈述 ∧ 揭示）两个正交源一致，或达到高置信阈值；单源不得定案。

**定义 320（解耦实验 DEX）** 实验 e 是**解耦的**，若 rank([J_θ(e) | J_ν(e)]) > rank([J_θ^passive | J_ν^passive])。最优解耦实验
e_D = argmax_e E[ rank gain ] 或 argmax_e Δκ_e（κ 的期望下降），
其中 J_θ(e)=∂y/∂θ，J_ν(e)=∂z/∂ν。已知参照实验通过提供「与 ν 独立的 θ 观测」加秩；二选一实验通过提供「与 θ 独立的 ν 观测」加秩。DEX 不要求两者同时可测，只要求新增一列不在既有列空间内。

**定义 321（需求鲁棒安全策略 NRS）** 当 b(ν) 未消解时，不用点估计优化，而取
π_NRS ∈ argmax_π CVaR_α^{ν~b}[ U_ν(π) ]，s.t. 风险 ≤ ε 且满足所有高概率需求下的硬约束（交集可行集）。
即「对冲需求」；当 supp b(ν) 退化为单点 ν₀ 时，NRS 退化为普通的期望效用最大化，也就是 R69/R68 的决策层。

**定义 322（三级归因与三级退化）** 每轮按顺序判定：
(1) 若 κ ≤ τ_κ（可辨识）且 U_epi 可消解 → 正常 FLUID 决策；
(2) 若 κ ≤ τ_κ 但需求后验仍有决策相关不确定性 → NRS 对冲，不做激进优化；
(3) 若 κ > τ_κ 且预算内无法执行解耦实验 / 解耦失败 / 被投毒 → 放弃归因，λ 单调不降地退化为 R69/R68 保守。
当 ν 已知（H(ν)=0）、θ 已观测（Σ_θ→0）时，DIAL 与 FLUID 逐指令相同；再叠加「永不交互」即退化为 R68。

**定义 323（双向吸收判据 DAB）** 定义两条独立残差：
- 行为似然残差 a_score（R69 的 FMA，测「动作是否像策略该生成的」）；
- 需求预测残差 r_need = E_{ν~b}[ log p(z_obs | ξ_obs, y_obs, ν) ]（测「观测行为是否像当前需求该产生的」）。
联合模式四种解释：(r_need 低, a_score 低)=一致；(r_need 高, a_score 低)=**需求变化而非漂移**；(r_need 低, a_score 高)=**漂移而非需求**；(r_need 高, a_score 高)=需解耦实验。该判据是 R69 定义 309「(r_res, Δa) 对偶」在需求侧的镜像。

**定义 324（证书 J_DIAL）** J_DIAL = (J_FLUID, need_ECE, U_cal^ν, κ, disentangle_rank, voe_ratio, calib_log_hash, dial_ver)。Valid ⇔ Valid(J_FLUID) ∧ need_ECE ≤ τ_need ∧ (κ ≤ τ_κ ∨ 已成功执行解耦实验) ∧ 可辨识性纪律满足 ∧ 统一预算未越界。

**定义 325（时序与自适应判定）** 控制频率下只做被动联合滤波（Laplace/粒子，零学习写操作）；仅当 CDX 越界、需求决策边际 ΔU 小或 DAB 报警时，才升采样并运行一次实验选择。默认不实验、默认点需求，保证常规路径与 R69 同延迟。

**定义 326（参与式审计 VQAuditor-D）** 在 R69 的 VQAuditor-I 上新增审计：是否把被污染的揭示证据当需求、是否在未校准通道上推断需求、是否用提问诱导/操纵用户、是否把需求变化误归因为传感器（或反之）、需求推断是否超出最小必要（隐私）。结论回灌 AuditBuf，作为下一轮 VoE 成本先验与 DEX 候选先验。

## 2. 关键算法骨架

```python
# IP-264/265 NIM+JCB：联合标定-需求信念（控制频率下零学习写操作）
class JointCalibNeedBelief:
    def __init__(self, theta_prior, need_prior, sensor_model, behavior_model):
        self.b_theta = theta_prior            # Laplace / particle over SE(3)^m x R^p
        self.b_nu    = need_prior             # need posterior, possibly multimodal
        self.sensor, self.behavior = sensor_model, behavior_model

    def update(self, xi, y, z):               # 被动更新，不学习参数
        self.b_theta = self.sensor.update(self.b_theta, xi, y)
        cred = need_evidence_credibility(self.b_theta)   # 坏尺子 -> 低权重
        self.b_nu = self.behavior.update(self.b_nu, xi, y, z, weight=cred)
        return self.confound_index()          # CDX: kappa

    def confound_index(self):                 # IP-267 CDX
        return canonical_corr(self.b_theta, self.b_nu)   # 线性高斯闭式

# IP-266 NEP：只计算投影到需求子空间上的标定不确定性
def need_projected_calib(belief, need_post, loss):
    J = jacobian(lambda th: expected_loss(loss, need_post, th), belief.mean_theta())
    return trace(J @ belief.cov_theta() @ J.T)     # U_cal^nu

# IP-268/269 VoE + DEX：统一预算下选“最值钱的实验”，优先加秩
def choose_experiment(belief, need_post, loss, budget_o):
    L0 = min_expected_loss(loss, belief, need_post)
    best = None
    for e in candidates(belief, need_post):            # ask / observe / known-ref / excitation
        if not budget_o.allow(e):                continue
        if not c_ras_wm.certify_info(e, belief.obs): continue   # 统一的 C-RAS-WM 认证
        L_after = expected_posterior_loss(loss, belief, e)       # 含 VoN/VoCal/VoD
        rank_gain = rank([J_theta(e), J_nu(e)]) - rank([J_theta_0, J_nu_0])
        voe = (L0 - L_after) - cost(e) + BETA_RANK * rank_gain  # 加秩有独立溢价
        if best is None or voe > best.voe: best = (e, voe)
    return best if best and best.voe > 0 else None               # 无利可图 -> 不实验

# IP-270 NEC：需求感知的标定激励设计（不做与需求无关的标定）
def design_calibration(belief, need_post, loss):
    J = need_jacobian(loss, need_post, belief.mean_theta())
    return argmin_trace(lambda c: J @ pinv(fisher(belief.traj + c) + I_prior) @ J.T,
                        candidates=calibration_maneuvers())

# IP-271 NRS：需求不确定时对冲，而不是对点估计精确优化
def need_robust_action(policy, need_post, alpha=0.1):
    return argmax_over_actions(
        lambda a: cvar(need_post, lambda nu: utility(policy, a, nu), alpha),
        feasible=intersection_of_hard_constraints(support(need_post)))

# IP-272 DAB：区分“需求变了”与“传感器漂了”
def dual_absorption(belief, need_post, xi, y, z, policy):
    r_need = expected_loglik(self.behavior, z, xi, y, need_post)
    a_score = -policy.log_likelihood(xi, belief.obs)          # 复用 R69 FMA
    return r_need, a_score        # (低,低)一致；(高,低)需求变；(低,高)漂移；(高,高)需解耦

# IP-276 主闭环（继承 R69，只在“目标层”插入 DIAL）
def DIAL_RAS_round(M, obs):
    z_t, o = M.mtm.forward(...)                    # R68/R69 一次前向
    M.belief.update(M.last_xi, M.last_y, M.last_z) # 被动联合更新
    kappa  = M.belief.confound_index()
    U_cal_nu = M.nep.need_projected_calib(M.belief, M.b_nu, M.loss)
    r_need, a_score = M.dab.dual_absorption(M.belief, M.b_nu, M.last_xi, M.last_y, M.last_z, M.fmp)

    need_exp = (kappa > TAU_KAPPA) or (decision_margin(M.b_nu) < TAU_MARGIN) or (r_need > TAU_NEED)
    e = M.voe.choose_experiment(M.belief, M.b_nu, M.loss, M.budget) if need_exp else None
    if e is not None:
        M.execute_certified(e)                     # 触碰参照 / 二选一 / 激励轨迹
        kappa = M.belief.confound_index()          # 期望加秩后复测
    # 2) 三级归因
    if kappa > TAU_KAPPA:                          # 仍不可辨识 -> 不强行归因

        k, lam, act = M.fluid_round(z_t, o)        # 逐指令复用 FLUID-RAS
    else:                                          # 需求仍有决策相关不确定性
        act = M.nrs.need_robust_action(M.fmp, M.b_nu)
        k, lam = safe_prefix(act, M, lam_floor_from(M.b_nu))

    M.vqa_d.submit_async(e, kappa, U_cal_nu, r_need, a_score, M.b_nu)
    return act, (kappa, U_cal_nu, decision_margin(M.b_nu))
```

## 3. 推导

**引理 19（需求投影定理）** 设损失 L(ξ, ν, θ) 对 θ 连续可微、在可信域内 L-Lipschitz。则对任意 θ ∈ credible set，
E[L(ξ*, ν, θ)] − E[L(ξ*, ν, θ̂)] ≤ tr(J_ν Σ_θ J_νᵀ)^{1/2} · (1 + o(1))，
其中 J_ν = ∂/∂θ E[L]。要点：**校准不确定性对决策的伤害只通过 J_ν 投影进入；与 J_ν 正交的 θ 方向（例如当前不做力敏任务时的力零点）对损失零贡献。** 系：标定预算应按 U_cal^ν 分配，而非按原始残差或 θ 的总熵分配——这是「需求决定精度该花在哪」的定量版本。

**引理 20（需求–标定可辨识性与吸收流形）** 在线性化观测 μ(ξ; θ, ν) = [h(ξ;θ); z̄(ξ;ν)] 下，(θ, ν) 可由被动数据局部辨识 ⇔ 合并雅可比 [∂h/∂θ, ∂z/∂ν] 列满秩。若秩亏，则存在非零方向 (δθ, δν) 使 h(ξ; θ+δθ) = h(ξ; θ) 与 z̄(ξ; ν+δν) = z̄(ξ; ν) 在所有被动采样 ξ 上同时成立；该方向即**吸收流形**，沿其移动不改变任何观测。故「需求被标定吸收」与「漂移被需求吸收」是同一秩亏的两种符号。系：被动估计器（含 R68 COF 与 R69 FMA）在吸收流形上不可分辨，必须用改变设计矩阵秩的主动实验。

**引理 21（双向吸收偏差的上界）** 线性高斯下，忽略 θ 偏移 Δθ 时需求估计的偏差为
E[ν̂ − ν] = (X_νᵀ X_ν)^{-1} X_νᵀ X_θ Δθ，
故 ‖bias‖ ≤ c·ρ(X_ν, X_θ)·‖Δθ‖，ρ 为两特征子空间的最大典型相关，也就是混淆指数 κ。对称地，忽略需求变化 Δν 时标定估计偏差 ≤ c'·κ·‖Δν‖。**κ 同时是两种吸收的放大系数**：κ→1 时，任一方的真实变化会被 1/(1−κ²) 量级地放大成另一方的伪变化。系：CDX 越界必须触发解耦实验或放弃归因，不能只降学习率。

**引理 22（需求信息增益与决策边际）** 设某信息动作 g 使需求后验熵降低 ΔH_ν，且当前最优动作与次优动作在需求空间上的决策边际为 ΔU。则相较按点估计行动，执行 g 后的期望后悔下降满足
E[ΔRegret] ≤ ΔU · min(1, √(2ΔH_ν/π))。
要点：**VoN 是「决策边际 × 可分离的熵」的函数，不是熵本身的函数。** 系：当 ΔU≈0（两种需求导致同一最优动作）时，再大的需求熵也不值得问——这正好是 R69 引理 16「可分的歧义才值钱」在需求层的对偶。

**定理 18（DIAL 严格包含 FLUID 与 R68）** 在 A99–A101（损失 Lipschitz、线性化观测、证据纪律成立）下：
(i) 当 ν 已知且 θ 已观测时，DIAL 的每一轮与 FLUID-RAS 逐指令相同；
(ii) 当再叠加「永不交互」时，与 R68 逐指令相同；
(iii) 在任意状态，DIAL 的最坏情况损失不超过「按点估计需求 + R69 保守」的策略，因为 NRS 在需求后验的 CVaR 上取最优且不放松任何硬约束；实验只重分配预算、不改变安全包络。
故 DIAL 是 FLUID/R68 在「需求已知、标定已知、永不实验」边界上的退化，而非并列替代。

**定理 19（需求鲁棒无突变）** 当 b(ν) 连续演化且 κ 越过阈值时，DIAL 切换到 NRS 或 R68 保守；因 NRS 的可行集为各高概率需求硬约束的交集，且 λ 单调不降，切换前后控制指令的跳变被 λ_floor 与 C-RAS-WM 前缀认证共同钳制在 ε_int 内。DAB 的报警只改变「是否实验/是否归因」，不跳过认证，故提交/换装不变式（R68 定理 15）保持。

## 6. 本轮最大风险

**一句话**：DIAL 全部归因能力押在「需求模型 ν 的假设类足够正确」上——**若 ν 的特征 φ 或先验本身错配，需求模型会把真实的传感器漂移当成「偏好变化」吸收掉，标定层又会把真实的需求变化当成「偏置」吸收掉，而 DIAL 会用一个秩检验为这个错误归因盖上「已解耦」的证书**；此时它比 R69 更危险，因为它不仅错了，还能证明自己没错——「不可辨识」必须是一个允许被说出口的结论，而不是用一次实验强行制造的可辨识假象。

**次级风险与缓解**：标定参照被伪造/激励轨迹投毒（ℰ_cal，已知参照的完整性校验 + 多参照一致）；用户表演行为操纵需求推断（陈述上限权重 + 揭示证据的多情境一致性 + VQAuditor-D）；隐私与最小必要（只推断决策相关 ν，不建全量用户画像）；实验预算被洞察/标定争抢（统一 VoE 排序 + 硬预算）；需求模型错配（OOD 需求检测 + 拒绝归因 + NRS 兜底）；实时性（默认不实验、κ 门控）。**若两个假设在安全且可负担的实验上真的观测等价，DIAL 的正确行为是承认不可辨识并保守对冲，而不是发明一个归因。**

**定义 317–318（统一实验与 VoE）** `e=(a,g,c)`；`VoE=L̂₀−E[L̂_e]−cost`，分解为 VoN/VoCal/VoD，统一由后验预测损失算；`VoE≤0` 不实验。

**定义 319（NIM）** `b(ν) ∝ b(ν)·Π p(z_i|ξ_i,y_i,ν)^{w_i}·p(stated|ν)`，`w_i=g(U_cal^ν_i, freshness)`；标定越不可信，揭示证据权重越低；陈述权重设上限 `w_stated≤w_max`；关键更新需陈述∧揭示两源一致或高置信。

**定义 320（DEX）** 解耦 ⇔ `rank([J_θ(e)|J_ν(e)])` 增加；`e_D=argmax Δκ_e`；已知参照加 θ 秩，二选一加 ν 秩。

**定义 321（NRS）** `π_NRS∈argmax CVaR_α^{ν~b}[U_ν(π)]`，s.t. 高概率需求硬约束交集；`supp b(ν)` 单点时退化为普通期望效用（R69 决策层）。

**定义 322（三级归因/退化）** (1) κ≤τ_κ 且可消解 → FLUID；(2) κ≤τ_κ 但需求仍不确定 → NRS；(3) κ>τ_κ 且无法/失败/被投毒 → 放弃归因，λ 单调不降退 R69/R68。ν 已知且 θ 已观测时与 FLUID 逐指令同；再「永不交互」即 R68。

**定义 323（DAB）** `r_need=E_{ν~b}[log p(z_obs|ξ_obs,y_obs,ν)]`，`a_score=−log p_θ(ξ_obs|o)`；四象限——(低,低)一致、(高,低)需求变、(低,高)漂移、(高,高)需解耦。是 R69 定义 309 在需求侧的镜像。

**定义 324–326（证书/时序/审计）** J_DIAL 并入 need_ECE、U_cal^ν、κ、disentangle_rank、voe_ratio；控制频率只做被动联合滤波，κ/ΔU/DAB 触发才实验；VQAuditor-D 审坏尺推断、诱导提问、误归因与隐私最小化。

## 3. 关键算法伪代码

```python
# IP-265 JCB：被动联合滤波（控制频率，零学习写操作）
class JointCalibNeedBelief:
    def update(self, xi, y, z):
        self.b_theta = self.sensor.update(self.b_theta, xi, y)
        cred = need_evidence_credibility(self.b_theta)     # 坏尺 -> 低权重
        self.b_nu = self.behavior.update(self.b_nu, xi, y, z, weight=cred)
        return canonical_corr(self.b_theta, self.b_nu)      # CDX kappa

# IP-266 NEP：只算投影到需求子空间上的标定不确定性
def need_projected_calib(belief, need_post, loss):
    J = jacobian(lambda th: expected_loss(loss, need_post, th), belief.mean_theta())
    return trace(J @ belief.cov_theta() @ J.T)              # U_cal^nu

# IP-268/269 VoE + DEX：统一预算选“最值钱”的实验，加秩有独立溢价
def choose_experiment(belief, need_post, loss, budget):
    L0, best = min_expected_loss(loss, belief, need_post), None
    for e in candidates(belief, need_post):                 # ask / observe / known-ref / excitation
        if not budget.allow(e) or not c_ras_wm.certify_info(e, belief.obs): continue
        voe = (L0 - expected_posterior_loss(loss, belief, e)) - cost(e) \
              + BETA_RANK * (rank([J_theta(e), J_nu(e)]) - rank([J_theta_0, J_nu_0]))
        if best is None or voe > best.voe: best = (e, voe)
    return best if best and best.voe > 0 else None          # 无利可图 -> 不实验

# IP-270 NEC：需求感知激励设计（不做与需求无关的标定）
def design_calibration(belief, need_post, loss):
    J = need_jacobian(loss, need_post, belief.mean_theta())
    return argmin(lambda c: trace(J @ pinv(fisher(belief.traj + c) + I_prior) @ J.T),
                  candidates=calibration_maneuvers())

# IP-271 NRS：需求不确定时对冲，而不是对点估计精确优化
def need_robust_action(policy, need_post, alpha=0.1):
    return argmax(lambda a: cvar(need_post, lambda nu: utility(policy, a, nu), alpha),
                  feasible=intersection_of_hard_constraints(support(need_post)))

# IP-272 DAB：区分“需求变了”与“传感器漂了”
def dual_absorption(belief, need_post, xi, y, z, policy):
    r_need  = expected_loglik(behavior, z, xi, y, need_post)
    a_score = -policy.log_likelihood(xi, belief.obs)        # 复用 R69 FMA
    return r_need, a_score    # (高,低)需求变；(低,高)漂移；(高,高)需解耦

# IP-276 主闭环（继承 R69，只在“目标层”插入 DIAL）
def DIAL_RAS_round(M, obs):
    z_t, o = M.mtm.forward(...); M.belief.update(M.last_xi, M.last_y, M.last_z)
    kappa = M.belief.confound_index()
    U_cal_nu = M.nep.need_projected_calib(M.belief, M.b_nu, M.loss)
    r_need, a_score = M.dab.dual_absorption(M.belief, M.b_nu, M.last_xi, M.last_y, M.last_z, M.fmp)
    need_exp = (kappa > TAU_KAPPA) or (decision_margin(M.b_nu) < TAU_MARGIN) or (r_need > TAU_NEED)
    e = M.voe.choose_experiment(M.belief, M.b_nu, M.loss, M.budget) if need_exp else None
    if e is not None:
        M.execute_certified(e)                              # 触碰参照 / 二选一 / 激励轨迹
        kappa = M.belief.confound_index()                   # 期望加秩后复测
    if kappa > TAU_KAPPA:                                   # 仍不可辨识 -> 不强行归因
        act = M.nrs.need_robust_action(M.fmp, M.b_nu)
        lam = max(M.efs.risk_scale(...), lam_floor_calm(...))
    elif decision_margin(M.b_nu) >= TAU_MARGIN:             # 需求清晰且可辨识
        k, lam, act = M.fluid_round(z_t, o)                 # 逐指令复用 FLUID-RAS
    else:
        act = M.nrs.need_robust_action(M.fmp, M.b_nu)
        k, lam = safe_prefix(act, M, lam_floor_from(M.b_nu))
    M.vqa_d.submit_async(e, kappa, U_cal_nu, r_need, a_score, M.b_nu)
    return act, (kappa, U_cal_nu, decision_margin(M.b_nu))
```

## 4. 推导

**引理 19（需求投影定理）** L 对 θ Lipschitz 时，`E L(ξ*,ν,θ) − E L(ξ*,ν,θ̂) ≤ tr(J_νΣ_θJ_νᵀ)^{1/2}(1+o(1))`。系：标定预算应按 `U_cal^ν` 分配，而非原始残差或 θ 总熵——「需求决定精度花在哪」的定量版。

**引理 20（可辨识性与吸收流形）** 线性化下 (θ,ν) 局部可辨 ⇔ `[∂h/∂θ, ∂z/∂ν]` 列满秩。秩亏时存在非零 `(δθ,δν)` 使所有被动观测不变——**吸收流形**。「需求被标定吸收」与「漂移被需求吸收」是同一秩亏的两种符号；R68 COF 与 R69 FMA 在流形上不可分辨。

**引理 21（双向吸收偏差上界）** 忽略 θ 偏移时 `E[ν̂−ν]=(X_νᵀX_ν)^{-1}X_νᵀX_θΔθ`，`‖bias‖≤c·κ·‖Δθ‖`；对称地有 `‖θ̂−θ‖≤c'·κ·‖Δν‖`。κ 是两种吸收的共同放大系数，`κ→1` 时任一真实变化被 `1/(1−κ²)` 量级放大成另一方的伪变化。系：κ 越界必须解耦或放弃归因，不能只降学习率。

**引理 22（需求信息增益与决策边际）** 信息动作使需求熵降 `ΔH_ν`、当前决策边际 `ΔU`，则 `E[ΔRegret]≤ΔU·min(1,√(2ΔH_ν/π))`。系：`ΔU≈0`（不同需求导致同一最优动作）时再大的需求熵也不值得问——R69 引理 16 的需求层对偶。

**定理 18（严格包含 FLUID 与 R68）** A99–A101 下：(i) ν 已知且 θ 已观测 ⇒ 与 FLUID 逐指令相同；(ii) 再「永不交互」⇒ 与 R68 逐指令相同；(iii) 任意状态最坏损失不超过「点估计需求 + R69 保守」，因 NRS 在需求 CVaR 上最优且不放松硬约束，实验只重分配预算、不改安全包络。DIAL 是 FLUID/R68 在「需求已知、标定已知、永不实验」边界的退化。

**定理 19（需求鲁棒无突变）** b(ν) 连续演化、κ 越阈切换 NRS/R68 时，NRS 可行集为各高概率需求硬约束的交集，λ 单调不降，切换跳变被 λ_floor 与 C-RAS-WM 前缀认证钳制在 ε_int 内；DAB 报警只改「是否实验/归因」，不跳过认证，故提交/换装不变式（R68 定理 15）保持。

## 7. 本轮最大风险

**一句话**：DIAL 全部归因能力押在「需求模型 ν 的假设类足够正确」上——**若 ν 的特征 φ 或先验错配，需求模型会把真实传感器漂移当成「偏好变化」吸收，标定层又会把真实需求变化当成「偏置」吸收，而 DIAL 会用一个秩检验为这个错误归因盖上「已解耦」的证书**；此时它比 R69 更危险，因为它不仅错了，还能证明自己没错——「不可辨识」必须是一个允许被说出口的结论，而不是用一次实验强行制造的可辨识假象。

**次级风险与缓解**：伪造参照/激励投毒（ℰ_cal：参照完整性校验 + 多参照一致）；行为表演操纵需求（陈述上限权重 + 多情境揭示一致性 + VQAuditor-D）；隐私与最小必要（只推断决策相关 ν）；预算争抢（统一 VoE 排序 + 硬预算）；需求模型错配（OOD 检测 + 拒绝归因 + NRS 兜底）；实时性（默认不实验、κ 门控）。**若两假设在安全且可负担的实验上真的观测等价，正确行为是承认不可辨识并保守对冲，而不是发明归因。**
