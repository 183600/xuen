# 第 47 轮（承接第 46 轮 v23；本轮灵感：具身智能 × 决策规划） · Embodied-Plan-Cert：证书可达性驱动的具身技能规划与规划级安全监护（五层架构 v11）

> 承接第 46 轮 v23 Memory-Safety-Voice。v23 把记忆检索、语音分发、指令-姿态绑定接入了感知-能量-安全闭环，但整套系统仍是「反应式」的：安全谓词只在**执行某一步时**检查（SAB），决策只有记忆复用或贪心模态效用，系统里没有「规划」这一层。这留下核心缺口 H5：**系统无法在动作序列层面推理「哪些目标是可被认证地达到的」**。具身智能强调智能来自身体-环境闭环中的可行动性（affordance），决策规划强调在动作序列上做带约束的搜索与重规划。两者合起来指向同一件事：证书不应只附着于单帧姿态，而应附着于**身体可执行的技能**，并沿**规划链**组合传播。于是本轮把「姿态证书」升级为「规划证书」：规划器在证书状态空间中搜索，只有每步前置证书被当前证书蕴含、且链式风险满足机会约束的技能序列才被签发；执行时用规划级监护器逐步校验链，一旦断裂就切应急分支或重规划，而不是直接 fail-closed 死锁。

## 0. 直觉与动机

**灵感 1（具身智能 → 具身技能证书库）**
直觉：不是所有策略都能被身体「兑现」。机械臂的臂展、关节限位、载荷、末端刚度决定了哪些动作在物理上可行；感知层决定哪些动作在当前可观测性下可被认证。于是把动作建模为**带证书的具身技能** a=(Φ_pre^a, T^a, Φ_post^a, ρ^a, e^a)：前置证书谓词、证书变换、后置证书、共形校准的成功概率、能量成本。**可行动性 affordance** 即「当前证书状态 χ 蕴含的所有技能前置条件之集合」。技能库不是纯符号算子，而是被身体与传感器共同约束的可兑现动作。

**灵感 2（决策规划 → 证书可达性与机会约束搜索）**
直觉：规划不该只在名义世界模型上找「物理可行」，而要找「**认证可达**」。定义证书状态 χ_t 与证书可达集 Reach_H^α(χ_0,g)：存在长度≤H 的技能链，使目标 g 被末端证书覆盖、链式风险 ≤ α、能量 ≤ 预算。把规划从「可达性」升级为「证书可达性」，用 best-first 搜索 + 风险剪枝。更关键：把**主动感知当作规划动作**——当某分支因证书过宽不可达时，插入高信息价值（VoI）的就位/补证动作，主动缩小证书宽度，而不是被动等退化。

**灵感 3（具身智能 × 决策规划 → 规划级监护与应急树）**
直觉：执行时不再只查单步，而是检查「当前证书是否蕴含下一步前置」。若断裂，沿预计算的**应急规划树**（按观测/证书结果分支的与或树）切换；树也走不通才安全停机。这把 v23 的「执行期 fail-closed 死锁」降级为「规划期的分支选择」，安全从一次性判定变成可在链上持续维持的不变量。

**耦合升级**：五层架构 v11。根信任层把租约集合扩展为**证书状态** χ；L1 感知层输出证书宽度与分层；L2 上下文/记忆层不仅检索模态，还检索**技能链先验与规划片段**；L3 新增**具身规划层** EPCP；L4 安全层从单步守卫升级为**规划级监护** CPM + 应急树；L5 数据层采集规划断裂、组合失败与技能覆盖缺口样本，回灌 ESK 注册与 DCL。

## 1. 形式化定义（增量：定义 59–65）

**定义 59（具身技能证书）**
技能 a=(Φ_pre^a, T^a, Φ_post^a, ρ^a, e^a)。Φ_pre^a ⊆ C 是证书状态上的可认证前置谓词（含运动学可达包络、所需感知层 ω、能量租约余量）；T^a: C→C 是证书变换，由标定运动学/动力学与感知增益表导出；Φ_post^a 是后置证书条件；ρ^a∈[0,1] 为共形校准成功率；e^a 为能量成本。称 a 在 χ 上**可发动**，当且仅当 χ ⊨ Φ_pre^a。

**定义 60（证书状态与证书宽度）**
χ_t=(P_t, ℓ_p, ℓ_e, ω_t, D_t)，D_t 为数据护照。Cert(χ_t) 表示所有租约有效且 P_t 非空。证书状态空间记为 C，证书宽度 rad(χ_t)=rad(P_t)。**可行动集** Aff(χ)={a : χ ⊨ Φ_pre^a}。

**定义 61（规划证书与链式 soundness）**
规划 π=a_1…a_k，χ_i=T^{a_i}(χ_{i-1})。规划证书 Π_π=∧_{i=1}^{k}(χ_{i-1} ⊨ Φ_pre^{a_i})。链式风险 r(π) 必须由**联合校准**给出，禁止独立乘积：
r(π)=Q_{1-α}(Σ_i 𝟙[fail_i] | 校准集) 或保守上界 r(π)≤Σ_i ρ_fail^{a_i}+κ·Cov(π)，其中 Cov 为技能失败相关项。
**规划 soundness**：若 r(π)≤α 且执行监护每步成立，则 P(执行全程不违反证书 | π) ≥ 1−α。

**定义 62（证书可达性）**
Reach_H^α(χ_0,g)={π : |π|≤H, g⊆Φ_post^{a_k}, r(π)≤α, energy(π)≤E_avail}。目标 g **可认证达到** 当且仅当该集合非空。

**定义 63（具身决策目标）**
π*=argmax_π E[U_g(π)]，约束 π∈Reach_H^α，其中
U_g=𝟙[g 达成]−λ_c·viol−λ_e·energy−λ_t·T−λ_r·replan。
把规划级违规、能量、时间、重规划次数一并纳入目标，避免「为省能量而把风险推给下游」。

**定义 64（认证信息动作与 VoI）**
动作 a 的证书增益 Δcert(a)=E[rad(χ)−rad(T^a(χ))]_+/rad(χ)，信息价值
VoI(a)=Δcert(a)/(e^a+ε)。
规划器仅在某分支因证书过宽而不可达时，才插入高 VoI 的感知/就位动作；由此**主动感知成为规划的一部分**，而非独立调度器。

**定义 65（应急规划树）**
应急树 π_c 是以观测/证书结果为分支的与或树。**鲁棒**当且仅当每个叶子要么使 g 可认证达到，要么是安全停机 SafeHalt。执行监护断裂时沿树按当前 χ 切换；无可用分支则 SafeHalt。

## 2. 三大新增产出与既有 IP 升级

**IP-69 EPCP（Embodied Plan-Cert Planner）**
- 证书状态空间 best-first/A* 搜索，节点=(χ, plan, risk, energy)
- 风险剪枝：r(π)>α 或 energy>E_avail 即剪；用联合风险表而非乘积
- 主动补证：margin(χ)<τ_margin 时插入高 VoI 的 certifying skill
- 输出 CertifiedPlan(π, r, χ_end) 或 None（转应急树 / SafeHalt）
- 增量重规划：执行断裂时从当前 χ 重搜，复用已认证前缀

**IP-70 ESK（Embodied Skill Certificate library）**
- 技能注册：每个技能带前置/后置证书、可达包络、能量成本
- 共形校准：独立审计集校准 ρ 与证书变换误差，覆盖率不达标即拒绝注册
- 组合校准：维护技能对/链的联合失败表，供 joint_risk 查表
- 版本化与漂移检测：技能包/标定变更触发重新注册与回归审计

**IP-71 CPM（Certificate Plan Monitor & Contingency）**
- 规划级监护：每步校验 χ_{i-1} ⊨ Φ_pre^{a_i} 与 Cert(χ_i)
- 断裂处理：切应急树分支 → 增量重规划 → SafeHalt（三级降级）
- 主动补证：线上 margin 过低时插入 certifying action 再继续
- 与 CAR 级联：SafeHalt 触发根信任层 fail-closed，禁止无证书执行

**既有 IP 升级**
IP-63 ECPS：受 EPCP 的感知预算请求驱动，返回「该模态下可达的证书宽度」，而非贪心效用。
IP-66 MVR：记忆条目扩展为技能链片段 (plan_fragment, χ, outcome)，支持规划片段检索与复用。
IP-68 SAB：从单指令绑定升级为**规划级绑定**，逐步校验 B(v, P_t) 与 plan 一致性。
IP-62 CCA：新增**组合 soundness 红队**——注入技能间相关失败、分布漂移、链式校准失效。
IP-51 CAR：守卫对象从当前 P_t 扩展为规划证书 Π_π 的不变量；监护断裂即 fail-closed。
IP-61 DCL：采集规划断裂点、覆盖缺口技能、联合失败样本，回灌 ESK 注册。
IP-45 总线：新增 plan-cert / skill-registry / replan / contingency 话题。

## 3. 算法骨架

EPCP 每次规划调用：
1. 读证书状态 χ_0、目标 g、证书预算 (H, α, E_avail)
2. 初始化优先队列，节点按 U_g 上界排序
3. 弹出节点：若 g 被覆盖且 r≤α → 签发 CertifiedPlan
4. 否则枚举 Aff(χ) 中技能；若 margin<τ_margin 先注入 certifying skill
5. 对每个技能算 χ'=T^a(χ)、r'=joint_risk(π+[a])、e'；剪枝非法分支
6. 队列空 → 返回 None，转应急树或 SafeHalt

执行期由 CPM 监护：逐步校验前置蕴含与 Cert(χ_i)，断裂则切应急分支 / 增量重规划 / SafeHalt；CAR 保证任何无证书执行都被拒绝。

## 4. 本轮最大风险

**一句话**：规划 soundness 的全部保证都建立在链式风险 r(π) 的**联合校准**之上，一旦用逐技能独立乘积近似而忽略技能间的相关失败（同一姿态误差、同一遮挡、同一能量骤降会同时打穿多个技能），1−α 会系统性失真，系统会自信地签发实际不安全的规划链；因此必须以链级联合失败表或带相关项上界合成风险，并用独立审计集验证组合覆盖率，覆盖不足时退化为最保守的逐步单技能执行。

## 2. 关键算法 伪代码

### IP-69 EPCP
```
def plan_cert(chi0, g, skills, H, alpha, E_avail, tau_margin):
    open = PQ(); open.push(Node(chi0, plan=[], risk=0.0, energy=0.0))
    while open and budget_ok():
        n = open.pop()
        if goal_covered(g, n.chi) and n.risk <= alpha:
            return CertifiedPlan(n.plan, n.risk, n.chi)
        if len(n.plan) >= H: continue
        for a in skills:
            if not entails(n.chi, a.pre):
                if margin(n.chi) < tau_margin:
                    for c in certifying_skills(n.chi):        # 主动感知=规划动作
                        enqueue(open, apply(n, c), alpha, E_avail)
                continue
            chi2 = a.T(n.chi)
            risk2 = joint_risk(n.plan + [a])                  # 联合校准，禁止乘积
            e2 = n.energy + a.e
            if Cert(chi2) and risk2 <= alpha and e2 <= E_avail:
                enqueue(open, Node(chi2, n.plan + [a], risk2, e2), alpha, E_avail)
    return None                                               # 不可认证 → 应急树/SafeHalt

def enqueue(open, node, alpha, E_avail):
    ub = expected_utility_upper(node) - lambda_c*node.risk \
         - lambda_e*node.energy - lambda_t*len(node.plan)
    open.push(node, priority=ub)
```

### IP-70 ESK
```
def register_skill(a, audit, alpha_i, tol=0.02):
    rho_hat, q = conformal_calibrate(a, audit, alpha_i)
    cov = empirical_coverage(a, audit)
    if cov < (1 - alpha_i) - tol:
        return Reject("coverage_gap", cov)
    a.rho, a.risk_bound = rho_hat, q
    registry.add(a, version=next_version())
    joint_table.update_from_audit(a, audit)                   # 累积链级联合失败
    return Accept(a)

def joint_risk(plan):
    key = tuple((s.id, s.version) for s in plan)
    if key in joint_table:                                    # 链级经验校准
        return joint_table.quantile(key)
    return min(1.0, sum(s.risk_bound for s in plan) + kappa*corr(plan))
```

### IP-71 CPM
```
def execute_plan(pi, chi, g):
    for i, a in enumerate(pi.plan):
        if not entails(chi, a.pre):
            return replan_or_contingency(pi, chi, i, g)
        outcome, chi = a.execute(chi)
        if not Cert(chi):
            return safe_halt(chi)
        if margin(chi) < tau_margin and i + 1 < len(pi.plan):
            chi2 = active_certify(chi, pi.plan[i+1].pre)
            if chi2 is None:
                return replan_or_contingency(pi, chi, i, g)
            chi = chi2
    return 'goal', chi

def replan_or_contingency(pi, chi, i, g):
    if pi.contingency and branch_exists(pi.contingency, chi):
        return execute_plan(branch(pi.contingency, chi), chi, g)   # 一级：应急树
    pi2 = plan_cert(chi, g, skills, H, alpha, E_avail, tau_margin)
    if pi2 is not None:
        return execute_plan(pi2, chi, g)                           # 二级：重规划
    return safe_halt(chi)                                          # 三级：SafeHalt
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| EPCP 搜索 | 最坏 O(\|A\|^H)，风险/能量剪枝后近 O(b^d) | O(\|open\|) | 签发仅当 r(π)≤α 且能量可行 |
| joint_risk | O(1) 查表 / O(\|calib\|) 核估计 | O(\|joint_table\|) | 链级联合校准，含相关项 |
| ESK 注册 | O(\|audit\|·d) | O(\|registry\|) | 审计覆盖率 ≥1−α_i 才可注册 |
| CPM 监护 | O(k) 每规划，O(1) 每步 | O(1) | 前置蕴含 + Cert 不变量逐步维持 |
| 主动补证 | O(\|A_cert\|) 插入 | O(1) | VoI>0 且证书宽度严格下降才插入 |

**正确性定理**：设所有技能经 ESK 注册且审计覆盖率 ≥1−α_i，链式风险由 joint_table 或带相关项上界给出。若 EPCP 返回 π 且 r(π)≤α、energy(π)≤E_avail，且 CPM 在每步维持 χ_{i-1}⊨Φ_pre^{a_i} 与 Cert(χ_i)，则 P(执行全程不违反证书)≥1−α。若 EPCP 返回 None，系统进入应急树或 SafeHalt，绝不执行未认证技能序列；CAR 对所有无证书执行 fail-closed。注意：**该定理不假设技能失败独立**，独立性由 joint_risk 的联合校准/相关项显式处理。

| E119 主动补证收益 | 单位焦耳证书宽度缩减、任务时间 | 宽度缩减 ≥20%/J；时间不劣于基线 10% |
| E120 100h 长程具身闭环 | 任务成功率、安全违例、未认证执行 | 成功率 ≥95%；违例 0；未认证执行 0 |

**回退策略**：E115 某技能覆盖 <1−α_i−2% → 撤销注册，规划器禁用该技能；E116 校准曲线偏离 → 改用带相关项上界并收紧 α；E117 规划不如基线 → 缩短 H、关闭主动补证走保守前缀；E118 重规划时延超阈 → 预展开应急树深度+1、缓存联合风险表。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 技能间相关失败被独立乘积低估 | 高 | joint_table 链级校准 + 相关项上界；审计集验证组合覆盖率 |
| 技能库覆盖缺口导致规划不可达 | 高 | 覆盖缺口样本回灌 ESK；缺口技能标注降级，规划走应急分支 |
| 证书过保守致规划抖动/频繁补证 | 中 | 设 VoI 门限与补证预算；margin 回滞避免反复插入 |
| 标定/技能版本漂移使联合表失真 | 中 | 版本化注册；漂移检测触发重校准与回归审计 |
| 规划级监护带来时延 | 低 | 每步 O(1) 校验；前置蕴含预编译为位图 |

## 6. 本轮最大风险

**一句话**：整链 soundness 依赖 joint_risk 的联合校准，若工程上为省算力退化为「逐技能共形校准 + 独立乘积」，相关失败（同一遮挡/姿态误差/能量骤降同时打穿多技能）会让 1−α 保证名存实亡，系统会自信签发实际不安全的规划链；因此必须坚持链级联合失败表或带相关项上界，并用独立审计集持续验证组合覆盖率，覆盖不足时退化为最保守的逐步单技能执行。
