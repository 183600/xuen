# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配多模态策略 × 主动多模态交互」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「成功率」×「强化学习」）

> R69 给闭环装上了「消歧层」：把不确定性拆成 aleatoric/epistemic，用流匹配多模态策略 + 主动交互去消解，预算内消解失败才退回 R68 的保守铁律。但它始终只优化两个量：**风险（越小越好）** 与 **歧义（值不值得查）**。它从未问过——**我到底要「成功」什么？这个「成功」是谁定义的？它能不能被刷分？我估出来的成功率本身准吗？**
>
> 本轮两个灵感正面撞上这块空白：
> - **强化学习**是把「长期累计成功」当作优化对象的机器——它第一次让闭环从「别出错」升级为「**去完成**」；
> - **成功率**则是这个目标最自然的度量——但它恰恰是最容易被 Goodhart 化的度量：回合级、稀疏、延迟、可删失，且定义它的验证器本身可被攻击。
>
> 核心命题：**把「成功」本身当作一个需要证书的测量量（measurand）。本轮不引入一个更强的优化器，而引入一个「只允许优化已认证成功估计」的约束——安全是可行域（shield），成功是目标（但只优化其悲观下界 LCB），成功估计器必须与策略架构独立（Objective Lock），任何不可信（RCE 越界 / ESS 过低 / 漂移 / 投毒 / 契约不可核验）时整层 no-op、逐指令退化为 R69→R68。** 命名 **VERDICT-RAS**（Verified Episodic Return under Distribution-shift, Interval-Calibrated Trust）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「该向谁求证」，R70 问「**我追求的『成功』本身可信吗、能不能被刷分**」——RL 不是给闭环换一台更快的引擎，而是给它装一个会审计自己目标的陪审团。

## 0. 直觉与动机

**灵感 1（RL → 闭环第一次从「规避」转向「达成」）**
直觉：R66–R69 是一条不断加保险的负向工程——谁控制、未来怎样、测量准不准、向谁求证，全都在把「坏结果」的概率往下压。但一个只会刹车的系统不会完成任务。RL 给的正是缺失的正向目标：把「一段回合里是否完成目标」的累计回报当作要最大化的量。于是出现一个漂亮的对称：**安全性是约束（constraint），成功率是目标（objective）**——两者不被塞进同一个加权和，而是进入 CMDP（约束马尔可夫决策过程）的两个不同位置：安全进可行域，成功进目标函数，永不标量兑换。

**灵感 2（成功率 → 最危险的目标度量）**
直觉：成功率的诱惑恰在于它太像「安全」——一个标量、可监控、能写进 KPI。但它有三个致命结构：(a) **回合级、稀疏、延迟**，信用分配困难；(b) **可删失**——系统能在失败前中止、能不记录难例，于是「成功率上升」可能只是「难例消失」（幸存者偏差）；(c) **可被验证器欺骗**——RL 是最强的 Goodhart 机器，只要「成功」由一个可被优化的验证器判定，策略迟早会找到验证器的盲点。**优化的对象一旦是度量本身，度量就不再是度量，而成了被攻击面。** 这直接把 R69 的「投毒交互」升级为「投毒奖励」。

**灵感 3（把成功当测量量 → R68 校准哲学的对象转移）**
直觉：R68 校准了传感器，R69 校准了模态权重，却从未校准「目标」。本轮的关键姿态是 **measurand 转移**：把成功/回报当作一个测量量 \hat p_success——它有偏差、有方差、有分布漂移、有校准误差。于是 R68 的 ECE 有了兄弟 **RCE（回报校准误差）**；R68 的「不确定就收紧」有了目标侧版本 **悲观下界（只优化 LCB）**；R68 的「第二意见」有了目标侧版本 **独立验证器 + held-out 评估**。RL 不被禁止，但只能在一个「已校准且悲观」的成功估计上做梯度上升。

**灵感 4（估计器-策略分离 → 对抗 Goodhart 的结构性解）**
直觉：R68 用第二条通道防「标定吸收」，R69 用 k 个正交证据防「交互投毒」。目标侧同理：**只要策略与「判定成功」的验证器共享参数或共享证据，Goodhart 就不是风险而是必然**——策略会过拟合验证器而牺牲真实效用。所以本轮给出最强的一条架构不变式：**Objective Lock（目标锁）**——策略梯度绝不回传到验证器，验证器与估计器只吃 held-out 证据、走不同模态。这是把「第二意见」从临时技巧升级为架构约束。

**灵感 5（信息动作 = 安全探索通道 → 复用 R69）**
直觉：RL 最危险的动作是探索——ε-greedy 在物理动作空间里抖动，等于拿身体试错。但 R69 已经给了我们一套天然的、可认证的探索原语：**看、问、触、等**。于是本轮规定：**探索只能在 𝒜_info 里发生**——你可以多看两眼、多问一句、多探一次，但不能为了探索而乱动。这把「探索」从 aleatoric 的乱试，变成 epistemic 的求知；探索的代价付在「观察/询问」上，而不是「风险」上。这是 R69 与本轮最自然的接口。

**灵感 6（均值成功 ≠ 安全成功 → 尾部与分层）**
直觉：「成功率 95%」可以和「5% 的回合灾难性失败」并存；全局成功率上升也可以靠牺牲一个子群（某类场景直接放弃）实现。所以本轮同时约束并报告三样东西：**CVaR（尾部）**、**最差分层的成功率**、以及不确定性下的**悲观 LCB**。一个只最大化平均成功率的策略，正是 R68 保守主义最该恐惧的东西——它会把「罕见但致命」的概率当作可兑换的成本。

## 1. 形式化定义（增量：定义 310–326）

**定义 310（VERDICT-RAS 总览与五不变式）** VERDICT-RAS = (SOC, CSR, RCE, PESS, OPE-FLOW, SPEC, CVaR-S, GAMING, VQAuditor-R, RAS-WM††)。五不变式：
(i) **安全 = 可行域**：安全永不进入标量目标，只作为 shield/约束（继承 R66–R69，见定理 19）；
(ii) **目标可核验**：成功必须由独立 verifier 依 objective_contract 判定，contract 有 hash、可追溯、可反驳；
(iii) **Objective Lock（估计器独立性）**：策略与成功验证器/估计器不共享参数、不共享证据分区（E_policy ∩ E_eval = ∅），策略梯度不流经 verifier；
(iv) **悲观优化**：只优化成功的 LCB，不优化点估计（定义 314）；
(v) **实时零学习写操作（强化版）**：RL 更新只允许在控制周期边界异步提交且必须过准入（定义 325）；实时热路径只做推理，延迟与 R69 持平。

**定义 311（成功目标契约 SOC）** 回合 τ 的成功指示 o_succ = Verify_κ(τ) ∈ [0,1]，由验证器 κ 依契约 C = (φ, H, δ, S, κ_id, hash) 判定：φ 为可判定谓词、H 为时域、δ 为容差、S 为分层集合。成功率 p_π(s0) = E_π[o_succ | s0]。**目标歧义** U_obj = 真实效用与 φ 之间未被契约覆盖的部分；U_obj 大 ⇒ 该回合不计入奖励（保守），以免优化一个被误解的目标。

**定义 312（约束成功优化 CSR / CMDP）** CMDP = (S, 𝒜_+, P, r = o_succ, c = c_safe, γ)。目标：max_π E_π[Σ_t γ^t r_t]，s.t. E_π[Σ_t γ^t c_t] ≤ d（硬不变量取 d=0）且 a_t ∈ SafeSet(s_t)（C-RAS-WM 认证）。**关键：安全是可行集投影（shield），不是拉格朗日软惩罚**；只有可商议的性能约束才进拉格朗日。

**定义 313（回报校准 RCE 与分层校准）** 设 V_ψ(s) 预测「从此状态起成功」的概率/回报。按分箱 m：RCE = Σ_m (n_m/N)|p̂_m − p̄_m|（ECE 的回报版）。分层 RCE_s 按 S 中每层计算；**任一安全关键层 RCE_s > τ_rce ⇒ 冻结更新**。理由：RL 自举在自己的价值上，价值高估 = 系统性乐观 = 安全隐患。

**定义 314（悲观成功率估计 PESS / LCB）** \hat p_LCB(s) = \hat p(s) − β1·σ_V(s) − β2·D_shift(s) − β3·(1 − ESS/ESS_min)_+。优化目标为 Σ \hat p_LCB，而非 Σ \hat p。系：在支撑重叠不足时，乐观策略会追逐「估出来高、实际低」的动作；悲观策略只在「最坏也还行」时前进。

**定义 315（基于流似然的离策略评估 OPE-FLOW）** 行为策略 π_b = R69 的 FMP。对 held-out 轨迹 ξ_i：w_i = π_θ(ξ_i|o_i)/π_b(ξ_i|o_i)（用定义 301 的流似然比）。ESS = (Σw)²/Σw²。若 ESS < ESS_min ⇒ OPE 无效 ⇒ 本轮不更新。D_shift 由 (r_res, Δa) 对偶通道（R69 定义 309）+ 协变量漂移检测给出。

**定义 316（安全探索通道 SPEC）** 允许的探索动作集 Ω_explore ⊆ 𝒜_info（注视/探针/问句/等待）外加低风险信息型子轨迹；**禁止在物理任务动作空间做 ε-抖动式探索**。任何探索偏差必须过 C-RAS-WM 认证且落在 Ω_info。探索 = 求知，而非拿身体试错。

**定义 317（CVaR-成功与尾部约束）** 以 CVaR_α(o_succ)（低 α 分位）或 P(灾难失败) ≤ ε_cat 作为约束/报告量。禁止只报均值成功率（均值-尾部可分离，见引理 22）。

**定义 318（奖励/目标投毒威胁 ℰ_gaming）** (a) wireheading（自报成功、篡改奖励通道）；(b) 代理刷分（Goodhart 验证器）；(c) 删失失败（失败前中止/不记录）；(d) 幸存者偏差（只留成功回合）；(e) 验证器对抗样本。并入 AIC：ℰ_VERDICT = ℰ_FLUID × ℰ_gaming × ℰ_drift。

**定义 319（独立成功审计 VQAuditor-R）** 审计「报告成功 vs 核验成功」之差、删失率、分层成功率差、ESS 门、验证器被攻击迹象。结论回灌 AuditBuf，成为下一次 RL 准入的先验。独立性由定义 310-iii 强制。

**定义 320（证书 J_VERDICT）** J_VERDICT = (J_FLUID, verified_success, RCE, ESS_min, CVaR_α, min_stratum_success, objective_contract_hash, gaming_audit, drift_flag, verdict_ver)。Valid ⇔ Valid(J_FLUID) ∧ RCE ≤ τ_rce ∧ ESS ≥ ESS_min ∧ 无 gaming_audit 告警 ∧ 安全约束满足。

**定义 321（非平稳与滑窗成功估计）** 成功率非平稳；用滑窗估计 + 变点检测（CUSUM / Page-Hinkley）。drift_flag = 1 ⇒ 触发悲观/冻结，回退到 R69 的保守行为（继承 R68 的慢漂移思想）。

**定义 322（Objective Lock 的形式化）** 存在证据分区 E = E_policy ⊔ E_eval；verifier κ 与估计器 ψ 仅可读 E_eval；策略 π_θ 仅可读 E_policy；∂L_RL/∂κ = 0；π 与 κ 的参数集不相交。违背任一条 ⇒ 视为无效训练（定义 325 拒绝准入）。

**定义 323（分层成功与最差分层）** p_succ^(min) = min_{s∈S_safety} p_succ(s)。优化/报告必须包含 p_succ^(min)，防止「全局上升、子群归零」。（对应 R68 的分层校准。）

**定义 324（成功-安全 Pareto，禁止标量化）** 维护 (success, safety) 的 Pareto 前沿；部署只在前沿的安全侧选点。**显式禁止** λ·success − (1−λ)·risk 这类把安全当可兑换项的写法。（继承 R69「不做简单加和」的姿态。）

**定义 325（RL 更新准入 RLG）** 一次更新被接纳当且仅当：RCE ≤ τ_rce ∧ ESS ≥ ESS_min ∧ drift_flag = 0 ∧ gaming_audit 通过 ∧ 更新后策略在 SafeSet 内可行（用 shield 验证）∧ 异步提交（不在热路径）。否则 **no-op**：策略保持，闭环逐指令退化为 R69。

**定义 326（成功估计的第二意见对偶）** 与 R68/R69 对偶：R68 用 (r_res, Δa) 判「测量是否被标定吸收」；R70 用 (verified_success, reported_success) 之差判「目标是否被刷分」。若 reported 升而 verified 不升（或 ESS 降），判为 gaming 嫌疑。

## 2. 关键算法骨架

```python
# IP-264 SOC：成功目标契约与独立核验
class SuccessContract:
    def __init__(self, predicate, horizon, tol, strata, verifier, hash_):
        ...
    def verify(self, trajectory):                 # 只读 held-out / 独立 verifier
        return self.verifier.check(self.predicate, trajectory, self.horizon)

# IP-267 PESS + IP-268 OPE-FLOW：悲观成功率与可信度门
def pessimistic_success(V, sigma, shift, ess, ess_min, betas):
    pen = betas[0]*sigma + betas[1]*shift + betas[2]*max(0.0, 1 - ess/ess_min)
    return V - pen

def ope_flow(policy, behavior, heldout):
    lw = [policy.log_likelihood(x, o) - behavior.log_likelihood(x, o)
          for (x, o) in heldout]                  # log 重要性权重
    w  = softmax_normalize(lw)                    # 稳定化
    ess = (w.sum()**2) / (w**2).sum()
    return weighted_success(w, heldout), ess

# IP-272/325：准入 + 约束更新（安全是可行域，不是奖励项）
def gated_update(M, batch):
    V, sigma = M.value(batch.states)
    p_hat, ess = ope_flow(M.pi, M.fmp, M.eval_set)
    rce   = M.rce(M.value)                        # 回报校准误差
    drift = M.drift.detect()
    ok = (rce <= TAU_RCE and ess >= ESS_MIN and not drift
          and M.vq_auditor_r.pass_() and M.soc.verifiable())
    if not ok:
        return M.pi                               # no-op：逐指令退回 R69
    p_lcb = pessimistic_success(V, sigma, M.shift, ess, ESS_MIN, BETAS)
    for s, a, r in batch.transitions:
        if a not in M.c_ras_wm.safe_set(s):       continue   # shield
        grad = -advantage_lcb(p_lcb, s, a) * grad_logpi(M.pi, s, a)
        M.pi.update(grad)
    return M.pi

# IP-274 主闭环（实时路径只推理；学习异步、门控）
def VERDICT_round(M, obs, ep):
    # 1) R69 全闭环（流策略 + 交互消歧 + 安全认证）
    k, lam, mode, (U_ale, U_epi) = M.fluid.round(obs)
    # 2) 信息动作即探索：探索只发生在 𝒜_info
    if M.explore_due():
        g = M.spec.safe_probe(mode, U_epi)        # 认证过的看/问/触
        ep.log_info_action(g)
    # 3) 回合边界：独立核验 + 悲观估计 + 准入（热路径之外）
    if ep.terminated:
        o_succ = M.soc.verify(ep.trajectory)      # 独立 verifier
        M.audit_buf.push(o_succ, ep.reported_success)
        M.async_submit(gated_update, M, M.replay.sample())
    return k, lam, mode
```

## 3. 推导

**引理 19（悲观优于乐观，支撑失配下）** 设点估计 \hat p 在分布外状态上系统性高估 b>0。乐观策略选 argmax \hat p，其真实成功 p_true ≤ \hat p − b；LCB 策略选 argmax(\hat p − βσ) 且 βσ ≥ b 时，所选动作的真实成功 ≥ LCB，故支撑失配处乐观策略的后悔 ≥ b，而 LCB 策略无此下界损失。系：悲观不是保守主义审美，而是「估计不可信时唯一不放大误差的选择」。

**引理 20（Objective Lock 的必要性 / Goodhart 下界）** 若策略与验证器共享证据（E_policy ∩ E_eval ≠ ∅）或参数/梯度耦合，且策略容量与优化步数足够，则存在 π 使 reported success 上升而 true utility 不升甚至下降。思路：共享证据 ⇒ 验证器判定成为策略可影响量的函数 ⇒ 可构造在 E_policy 上「作弊」、在 held-out 上失效的策略。系：独立性不是工程洁癖，而是「reported ↑ ⇒ true ↑」这一蕴含成立的前提。

**引理 21（信息探索的安全性）** 若探索限制在 Ω_info 且每个 g 过 C-RAS-WM 认证，则任意探索轨迹的物理风险 ≤ ε_int；与 ε-greedy 在 𝒜_task 中抖动（可达 ε_task ≫ ε_int）相比，探索代价被转移到「观察/询问」维度。系：探索不再是安全与学习的零和，而是「用信息换信息」的过程（呼应 R69 的 VoI）。

**引理 22（均值-尾部可分离）** 存在两个策略 π⁺, π⁻ 使 mean_success(π⁺) ≥ mean_success(π⁻)，但 CVaR_α(success)(π⁺) < CVaR_α(success)(π⁻)。构造：π⁺ 以极小概率换取灾难失败、其余回合高成功，π⁻ 全部稳成。故只优化均值成功可与尾部安全冲突，必须显式约束尾部（定义 317）。

**定理 18（VERDICT 严格包含 FLUID 与 R68）** 当 RCE > τ_rce ∨ ESS < ESS_min ∨ drift_flag ∨ gaming_audit 告警 ∨ 契约不可核验时，RLG 使更新为 no-op，闭环逐指令退化为 R69（FLUID），进而按 R69 定理 16 退化为 R68。安全侧永不弱于 R69；成功侧仅在估计被认证时获得增益。⇒ R68 ⊂ R69 ⊂ R70（在「不学习」边界上逐指令相同）。

**定理 19（目标投毒下的安全不可侵）** 安全作为可行域投影（shield）而非奖励项，故无论奖励信号如何被对抗污染（wireheading / 代理刷分），策略输出始终 ∈ SafeSet；投毒至多降低 success（性能），不能越过安全包络。⇒ 「护盾保护身体，审计保护意义」——两类失效模式被结构性解耦。

**定理 20（报告成功的 PAC 界）** 在 Objective Lock 与 ESS 门下，用 held-out 独立评估的 reported success 满足 |p̂ − p_true| ≤ sqrt(log(2/δ)/(2N_eff)) + (1−ESS/N)_+·B（N_eff = ESS，B 为单样本回报上界；细节 A99）。故 ESS 门是「报告可信」的工程化充要条件。

## 6. 本轮最大风险

**一句话**：引入 RL 层，等于把整个栈变成一个「专业搜索成功定义漏洞」的机器——**护盾只能约束动作，约束不了「成功的意义」；一旦验证器成为新的单点真相，任何 reported↑ 与 true↑ 之间的缝隙都会被长期优化放大（Goodhart 近乎必然），最坏情况不是「学不会」，而是「学会了刷分且自认为成功」**——成功的测量被优化，测量就不再是测量。

**次级风险与缓解**：
1. **验证器自身被攻破** → Objective Lock（定义 322）+ 独立 held-out 证据 + VQAuditor-R 对抗审计；
2. **奖励通道在线篡改（wireheading）** → 奖励只走离线核验、热路径只读、自报成功永不直接入账（定义 311/318）；
3. **删失与幸存者偏差** → 强制记录中止/失败、删失率入证书、E308 偏差修正；
4. **非平稳导致旧成功率失效** → 滑窗 + 变点检测 + drift_flag 触发悲观/冻结（定义 321）；
5. **分层被牺牲** → 最差分层与 CVaR 硬报告、Pareto 安全侧部署（定义 317/323/324）。

# 第 70 轮产物 · 创新点清单 v1：VERDICT-RAS（Verified Episodic Return under Distribution-shift, Interval-Calibrated Trust：成功目标契约 × 约束强化学习 × 悲观成功率估计 × 目标审计；SOC×CSR×RCE×PESS×OPE-FLOW×SPEC×CVaR-S×GAMING×VQAuditor-R×RAS-WM††）

**定义 310（总览与五不变式）** 安全=可行域；目标可核验；Objective Lock（估计器独立）；悲观优化；实时零学习写（更新异步 + 过准入）。

## 3. 关键算法伪代码

```python
# IP-264 SOC：成功目标契约与独立核验
class SuccessContract:
    def verify(self, trajectory):                 # 只读 held-out / 独立 verifier
        return self.verifier.check(self.predicate, trajectory, self.horizon)

# IP-267 PESS + IP-268 OPE-FLOW
def pessimistic_success(V, sigma, shift, ess, ess_min, betas):
    return V - (betas[0]*sigma + betas[1]*shift
                + betas[2]*max(0.0, 1 - ess/ess_min))

def ope_flow(policy, behavior, heldout):
    lw  = [policy.log_likelihood(x, o) - behavior.log_likelihood(x, o)
           for (x, o) in heldout]
    w   = softmax_normalize(lw)
    ess = (w.sum()**2) / (w**2).sum()
    return weighted_success(w, heldout), ess

# IP-272/325：准入 + 约束更新（安全是可行域）
def gated_update(M, batch):
    V, sigma = M.value(batch.states)
    p_hat, ess = ope_flow(M.pi, M.fmp, M.eval_set)
    rce, drift = M.rce(M.value), M.drift.detect()
    ok = (rce <= TAU_RCE and ess >= ESS_MIN and not drift
          and M.vq_auditor_r.pass_() and M.soc.verifiable())
    if not ok:
        return M.pi                               # no-op：退回 R69
    p_lcb = pessimistic_success(V, sigma, M.shift, ess, ESS_MIN, BETAS)
    for s, a, r in batch.transitions:
        if a not in M.c_ras_wm.safe_set(s):       continue   # shield
        M.pi.update(-advantage_lcb(p_lcb, s, a) * grad_logpi(M.pi, s, a))
    return M.pi

# IP-274 主闭环（实时只推理；学习异步、门控）
def VERDICT_round(M, obs, ep):
    k, lam, mode, (U_ale, U_epi) = M.fluid.round(obs)     # R69 闭环
    if M.explore_due():
        g = M.spec.safe_probe(mode, U_epi)                # 认证信息动作=探索
        ep.log_info_action(g)
    if ep.terminated:                                     # 热路径之外
        o_succ = M.soc.verify(ep.trajectory)              # 独立 verifier
        M.audit_buf.push(o_succ, ep.reported_success)
        M.async_submit(gated_update, M, M.replay.sample())
    return k, lam, mode
```

## 4. 推导

**引理 19（悲观优于乐观）** 点估计在支撑外高估 b>0 时，乐观策略后悔 ≥ b；LCB 策略（βσ ≥ b）无此下界损失。系：悲观是「估计不可信时唯一不放大误差」的选择。

**引理 20（Objective Lock 必要性 / Goodhart 下界）** 策略与验证器共享证据或参数耦合 ⇒ 存在 π 使 reported success ↑ 而 true utility ↓。系：独立性是「reported↑ ⇒ true↑」的前提，非工程洁癖。

**引理 21（信息探索的安全性）** 探索限于 Ω_info 且每个 g 过认证 ⇒ 物理风险 ≤ ε_int；对比 ε-greedy 的 ε_task ≫ ε_int，探索代价被转移到观察/询问维度。

**引理 22（均值-尾部可分离）** 存在 π⁺,π⁻ 使 mean_success(π⁺) ≥ mean_success(π⁻) 但 CVaR_α(π⁺) < CVaR_α(π⁻)。故只优化均值可与尾部安全冲突，必须显式约束尾部。

**定理 18（VERDICT 严格包含 FLUID 与 R68）** 当 RCE>τ_rce ∨ ESS<ESS_min ∨ drift ∨ gaming 告警 ∨ 契约不可核验时，RLG no-op，闭环逐指令退化为 R69，再按 R69 定理 16 退化为 R68；安全侧永不弱于 R69，成功侧仅在估计被认证时获益。⇒ R68 ⊂ R69 ⊂ R70。

**定理 19（目标投毒下的安全不可侵）** 安全作为可行域投影而非奖励项，故奖励如何被对抗污染，输出始终 ∈ SafeSet；投毒至多降低成功，不能越过安全包络——「护盾护身体，审计护意义」。

**定理 20（报告成功的 PAC 界）** Objective Lock + ESS 门下，`|p̂−p_true| ≤ sqrt(log(2/δ)/(2N_eff)) + (1−ESS/N)_+·B`（N_eff=ESS，B 为单样本回报上界，A99）；故 ESS 门是报告可信的工程化充要条件。
