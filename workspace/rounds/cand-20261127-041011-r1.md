## 1. 直觉与动机（两个灵感的碰撞）

### 灵感 1（指令泛化 → 指令不是考题，是准考证）
直觉：官方五轴（F20）里没有「换一种说法」这一轴，所以把预算花在「听懂更多同义句」上是错配。指令真正的作用是**准考证**：它是 32 个任务里唯一稳定、低带宽、离散的任务身份信号。它的失败不是「听不懂」，而是两种边界问题：(a) **同义不稳**——评测句式与训练标注不同，路由漂移；(b) **异义不分**——32 个任务共享 Pack/Store/Organize/Arrange 等动词，StoreCups 与 StackBowls、PackPhone 与 PackBag 的指令只差目标物/容器，模型若依赖语言捷径就会整集做错任务。更关键：路由错误是**离散且灾难性的**（整集 0 分），而视觉/动作误差是**连续且优雅降级**的。反直觉结论：**指令泛化的目标不是"更懂语言"，而是"把离散决策从连续感知里隔离出来"，并用它去解锁同一模型内的任务级先验。**

### 灵感 2（模型量化 → 量化不是省算力，是买反应时间）
直觉：第 2 轮把量化当部署优化（fp8/INT8 降延迟）。但读完 chunk 语义（F22）后，真正的约束不是单步推理，而是 **(chunk 长度, 推理延迟, 反应延迟) 的三角权衡**：chunk 越长越能摊薄推理，但人为干扰轴（F20）要求越短的反应延迟；量化把推理延迟 L 降下来，就能在同等截止期下用**更短的 chunk**，从而更快重规划——这是量化对计分轴的直接贡献，而不是省电。第二个反直觉点：**PTQ 的标定集若用标称数据，量化本身就是一次隐藏的分布偏移**——评测五轴会制造激活离群，标称标定会在最需要精度的轴上 clipping。第三点：量化最先塌缩的往往不是动作 MSE，而是语言/语义的细粒度可分性——恰好是 32 任务路由最需要的（F26）。

### 统一（本轮核心命题）
指令泛化负责**离散决策层**（路由/相位/开合/guard），模型量化负责**连续执行层的预算**（视觉特征/动作/ODE 步数）。量化的最大风险正好落在指令的语义边界上（离散塌缩），所以两者必须联合设计：**离散决策用符号/高精度保护，连续感知与回归用低精度换反应时间。** 本轮把第 2 轮的「数据引擎胜负手」扩展为「数据引擎 + 决策-执行精度分层」。

## 2. 对第 2 轮痛点的增量修订

- 新增 **P9（指令分布偏移 + 任务混叠）**：指令不在五轴内，但路由错误会污染全部五轴；且语言捷径会削弱位置/背景/未见物品轴的视觉接地。

## 3. 研究问题（新增 Q9–Q11，Q1–Q8 保留）

- **Q9（指令双向边界）**：如何在 32 任务、动词高度共享的条件下形式化并测量「同义不变 + 异义可分」？路由的最小充分表示是什么（符号槽位/句嵌入/LLM 解析）？低置信如何优雅退化而不硬路由？
- **Q10（后果感知精度分配）**：给定模块级 bit-width 与延迟预算，如何以「保护最小语义边界」而非「最小化平均动作 MSE」为目标做量化配置？哪些模块必须高精度（路由、技能相位、夹爪开合、ODE 末端）？
- **Q11（量化红利再投资）**：量化把 L 降下来后，余量应投入「更短 chunk（反应）」还是「多采样动作共识（鲁棒）」？其边际收益如何用 L0/L1 代理在真机前排序？

## 4. 设计原则（新增 PR6、PR7）

- **PR6 后果分配律**：数值精度按「误差后果的连续性」分配。离散决策（任务路由、技能相位、夹爪开合、guard 触发）用符号逻辑/FP32/高精度保护；连续回归（视觉特征、动作轨迹）可激进量化。量化配置的目标函数是「最大化最小语义边界」，不是「最小化平均 MSE」。
- **PR7 指令低带宽信道律**：指令只用于锁定任务、选择先验、设置阈值；物体位姿/外观等感知信息必须来自图像。训练时做指令 dropout/替换，防止语言捷径。
- PR1–PR5 保留（第 1/2 轮）。

## 6. 本轮最大风险

**一句话**：把「指令泛化」当新增计分轴会错配预算（它不在官方五轴内）；更危险的是量化最先塌缩的恰是 32 任务的语义边界——离散、灾难性，而平均动作 MSE 对此几乎不敏感，若没有语义边界门禁，量化模型可能「指标更好、路由更错」。

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2）

> 检索日期：2026-11-26（第 1 轮）、2026-11-27（第 2 轮）、2026-11-27（本轮）；来源见 §5。承接 v1.1：I6 大改为 v3、I10 新增，I1/I2/I4/I8/I9 增量修订，I3/I5/I7 维持。清单只增改不重置。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I1 v3 考纲校准五轴增广引擎 ★★★★★
- **动机**：（v1.0/v2 保留）计分的 320 次真机评测每次都在 5 轴上偏离训练分布（F2/F20），泛化缺口是全局乘性损失。
- **本轮深化（量化标定复用）**：考纲增广集不只喂训练，还**兼作 PTQ 标定集**。理由（P10）：量化是隐藏的协变量偏移，标称数据标定出的 clipping 范围会在「未见物品/背景/干扰物」轴上失效。用 I1 的考纲卡采样标定样本，使激活范围覆盖评测支撑集——同一份「按考纲出模拟题」的工程同时服务训练与量化。
- **与现有方案差异**：直接 SFT 队伍用标称数据；盲目增广队伍用无校准随机化；量化队伍用标称标定。本点让增广、训练、量化共用一张考纲卡。
- **技术可行性**：高。考纲卡半自动构建：LLM 解析 wiki + 人工校对（32 × 10 分钟）；标定集只需 256–1024 帧/轴，成本可忽略。
- **所需资源**：分割/inpainting 1×24GB GPU；标定集复用增广输出，无新增下载。
- **落地步骤**：①32 张考纲卡；②背景/干扰物两轴放量；③外观/位置两轴 L0 消融先行；④剂量-响应定档；⑤导出「标定切片」给 I6 v3（每轴 256 帧，含未见物品外观合成）。
- **风险**：考纲卡与真实评测条件仍有偏差（缓解：单任务通道抽测 + 示例截图对齐）；位置重拼接物理不可行（L0「不可行动作占比」>5% 则降级为平移不变增广）；标定集若过度合成会高估量化鲁棒性（缓解：保留 20% 真实留出帧混合标定）。

### I2 v2.1 数据引擎 2.0：110 语料孪生迁移 + 加权共训 ★★★★★
- **动机**：单模型平均分被最弱任务支配（P1）；示教语料与质量双重浪费（P8）；任务混叠（P9）。
- **本轮增量（指令硬负例 + 标注审计）**：
  1. 保留 v2 三件事：孪生语料入训、官方 loader 加权 patch、示教质量加权。
  2. **新增指令硬负例表**：孪生任务/同动词任务的指令必须显式区分（如 StoreCups vs StackBowls vs PaperCupStacking），供 I10 的对比训练与路由混淆矩阵使用；孪生语料入训时**禁止**把 A 任务的指令配 B 任务的动作。
  3. **语言标注审计（F25）**：抽样核对每任务在数据内是一条还是多条指令、句式是否模板化——决定 I10 的收益上限与路由置信阈值。
- **与现有方案差异**：均匀混训把容量浪费在已会任务与低质示教上；本点诊断先行、孪生定向、权重受控、指令不混叠。
- **技术可行性**：高（frozen-VLM/LoRA 单卡起步，F11/F26）。
- **所需资源**：孪生子集 ≈1–2TB + 32 任务 ≈2TB；训练 1×24GB 起步、8×A100 上限。
- **落地步骤**：①孪生表 + 指令硬负例表；②语言标注审计；③下载孪生子集；④loader patch + 单元测试（batch 内任务频率验证权重生效）；⑤首轮共训；⑥族级 L0 验证正迁移后放量。
- **风险**：负迁移（孪生任务动态相反）——家族级 L0 消融、低权重起步、退步即裁剪；相机配置不一致——先抽样核对 4 相机命名/分辨率；指令硬负例若与真实标注冲突，以真实标注为准。

### I3 接触任务族关键点视觉伺服回退 ★★★★（维持）
- 六要素同 v1.0：通用 chunk 策略负责接近段、几何伺服负责接触段，同一策略服务内混合推理（PR2 边界待组委会确认）；`ee` 控制空间 + per-step 调用天然支持；开放词汇检测零训练起步；触发滞回 + 低置信回退。
- 本轮补充：孪生语料为接触段提供更多示教；**降级预案 I3'**：若混合推理被判违规，改为训练时辅助监督（伺服关键点作辅助标签），推理纯端到端。
- **与量化关系**：关键点/相位是离散决策，按 PR6 保持 FP32/高精度；视觉特征可量化，但接触段的末端位姿回归应保留 BF16。

### I4 v2 人手干预感知门控（修正） ★★★
- **修正依据（F22）**：`action_chunk_size` 在 metadata 固定，运行时不能按需变长/变短。v1.1 的「干预态短 chunk / 稳定态长 chunk」无法直接实现。
- **修正方案**：把「自适应 chunk」拆成两件可做的事：
  1. **部署期选 T_a**：由 I6 v3 的延迟-Pareto 选择固定 chunk 长度；T_a 越小，干预反应越快（反应延迟 ≈ T_a/f + 检测延迟）。
  2. **运行期尾部整形**：在 `get_action` 时若检测到人手进入（手部检测 + `obs_delta_indices` 历史栈），保持返回形状 (T_a, …) 不变，但把 chunk 尾部替换为安全保持/退让动作；状态机 INTERFERED→停持→重估→续做（PR3）。
- **与现有方案差异**：不再承诺无法实现的「可变 chunk」；改为在固定协议下用「选 T_a + 尾部整形」逼近反应性。
- **所需资源**：手部检测 1 人周；真机标定 1 个干预任务。
- **风险**：干预只能在 chunk 边界响应，T_a 过大则反应慢——这正是 I6 v3 量化红利要买的东西；若量化无法缩短 T_a，I4 的收益有限，优先级维持 ★★★。

### I5 v2 非标称示教合成 + 得分点对齐恢复 ★★★★（维持）
- **动机**：步骤分 = 官方得分点制（F17，每任务满分 100）；超时仍按进度计步骤分（F3）；数据集全成功、无失败示教（P8）。
- **核心产出**：①扰动重放（中间态注入位姿/抓取点扰动）；②跨段缝合（A 接近段 + B 抓取段）；③世界模型续写（WMA-0 仿真模式，缓）；④官方得分点做里程碑检测器，只有达成下一得分点的合成段才保留。

### I6 v3 后果感知选择性量化 + 量化红利再投资 ★★★★★（大改）
- **动机**：P6/P10/Q10/Q11。评测自托管推理（手册 §1.1），延迟/波动进入可信度评估（F23）；chunk 语义修正（F22）使「反应延迟」成为可优化量；量化若只按平均动作 MSE 选型，会牺牲离散任务边界。
- **与现有方案差异**：常规做法是「整模型统一 INT8/FP8，按 MSE 验收」；本点按 PR6 做**后果感知的模块级精度分配**，并以「语义边界不塌缩」为硬门禁，把省下的延迟再投资到更短 chunk（人为干扰轴）而非单纯省成本。
- **技术方案（五步）**：
  1. **模块清单**：vision tower、language encoder、mm projector、DiT attention/MLP、action head、gripper/phase head、state projector。
  2. **敏感度探针**：对每模块扫 {BF16, INT8-W8A8, INT8-W4A16, FP8-E4M3（仅 H100+）}，测四项：`d_act`（动作 MSE）、`d_disc`（相位/夹爪/任务离散决策错误率）、`m`（混淆任务对的最小语义边界）、`p99`（延迟）。
  3. **精度分配**：在 `p99 ≤ T_a/f` 与显存约束下，最大化 `min(m, 1−d_disc)`（min-max），而不是最小化 `d_act`。默认保护带：language encoder / 路由前端 / action head 末端 / ODE 最后 1–2 步用 BF16/FP16；vision tower 与 DiT 中段可 INT8（A100）或 FP8（H100+）。
  4. **标定与 QAT**：PTQ 标定集用 I1 考纲增广（含未见物品外观合成），per-channel/group scale，SmoothQuant 抑制激活离群；DiT 用 flow-matching loss + STE 做 QAT；ODE 精度调度（前段低精度、末段高精度）以抑制误差累积。
  5. **红利再投资**：由 `T_min = ceil(p99(L_Q)/(safety/f))` 选最小安全 chunk；优先把余量投入「更短 T_a（反应）」；只有当 L0 证明动作多峰是主因时，才投入「K 采样共识」。二者不叠加。
- **硬件现实**：A100 80G 有 INT8/FP16/BF16，**无 FP8 张量核**；FP8 需 H100/H200。预算按 A100 则默认 INT8 W8A8 + BF16 关键层；若租到 H100 再评估 FP8。BF16 若已满足截止期，量化的边际价值只剩 jitter/吞吐/反应性——必须用 Pareto 曲线证明，否则退回纯部署优化。
- **所需资源**：敏感度扫描 1 GPU 日；QAT 2–3 GPU 日/配置；标定集复用 I1（近零成本）；无新增数据下载。
- **落地步骤**：①模块敏感度表；②精度分配求解（贪心/背包）；③标定 + PTQ 冒烟；④DiT QAT；⑤chunk-延迟-反应 Pareto；⑥L0 门禁（语义边界 + 动作误差）；⑦单任务通道 A/B。
- **风险**：QAT 复杂/工具链对 Qwen-Image + DiT 覆盖不足（缓解：先 PTQ，QAT 仅 DiT；保留 BF16 回退）；量化后 jitter 反而变大（缓解：固定 shape、CUDA Graph、预热）；「指标更好但路由更错」（缓解：I8 v3 语义边界门禁，未过不上计分通道）。

### I9 v2 reset 期检索类比迁移 ★★★★
- **动机**：未见物品轴（同类不同外观）在 32 任务 × 2/10 次中全面出现；纯参数化泛化对新外观方差大。
- **本轮修正（与 I10 联动）**：reset 期先由 I10 得到任务 ID τ̂ 与置信度；检索索引**按任务分区**，只在 τ̂ 分区内做物体-动作参数最近邻；置信度低时退回全局索引或不注入先验。这样把「32 任务 × 全库检索」降为「单任务内检索」，显著降低误检索。
- **与现有方案差异**：纯通才策略靠训练分布平均化覆盖新物体；本点在 `reset()`（每 episode 一次，F18）做一次检索，把结果作软先验/门控偏置；零权重更新。
- **技术可行性**：中-高。嵌入库离线构建；reset 检索 <1s；episode 内零额外每步开销。
- **所需资源**：嵌入 1×GPU 日 + FAISS；1 人周工程。
- **落地步骤**：①物体库构建（首帧开放词汇检测裁剪）；②嵌入 + 索引（按任务分区）；③动作先验参数化（夹爪开度、接近高度/朝向、技能模式）；④reset 检索 + 软注入；⑤未见轴 L0 + 真机抽测。
- **风险**：误检索伤原本会的任务（先验仅软偏置 + 距离阈值 + I10 任务分区）；嵌入对同类不同外观不敏感（DINOv2 patch 池化 + 几何描述词）；合规性书面确认。

### I10 指令-程序路由 + 语义边界训练（新） ★★★★
- **动机（P9/Q9）**：指令是唯一稳定任务 ID（F21），但不在五轴内（F20）；32 任务动词高度共享，路由错误离散且灾难性；语言捷径会削弱视觉接地。目标不是「听懂更多说法」，而是「同义锁定同一任务、异义锁定不同任务，并把离散决策隔离于量化」。
- **与现有方案差异**：常规 VLA 把指令直接拼进 prompt，任务身份与感知特征在同一量化网络里纠缠；本点把任务身份提升为**显式的离散路由层**（符号+嵌入，FP32/离线），再以规范任务嵌入与先验注入同一模型，路由错误可检测、可回退、不受量化影响。
- **技术方案（四层）**：
  1. **离线任务程序库**：每任务 `{task_id, canonical, verb, target_object, receptacle, bimanual, key_phases, scoring_steps}`；由任务 wiki + 数据标注 + LLM 生成，人工校对。
  2. **释义库 + 硬负例**：每任务 LLM 生成 20–50 条释义（同义、语序、中英、礼貌/冗余），人工抽检；硬负例取同动词/同容器任务对（见 §1.1 表）。
  3. **路由**：符号槽位（正则/词典）+ 句嵌入最近邻（FAISS over 释义库）投票；输出 τ̂ + 置信度。置信度低于阈值时**不硬路由**，退回原始指令嵌入（优雅退化）。若评测指令为泛化/空模板，则转「视觉任务分类」分支（首帧场景→任务），语言仅作弱先验。
  4. **条件化与训练**：把 τ̂ 映射到规范任务嵌入，作为同一模型的语言条件；同时选择 I9 检索分区、I4 chunk 参数、I5 恢复先验、guard 阈值。训练时：①释义替换（同义不变）；②10% 指令 dropout（逼视觉接地）；③对比辅助损失（释义拉近规范嵌入，硬负例推远），**不**用「指令交换+错误动作」监督（避免教坏动作）。
- **与单模型合规**：全程一个模型；路由只做推理期条件化与先验选择，不切换 LoRA/专家（F24）；需向组委会书面确认「指令解析+先验选择」属于单模型内的合规组件。
- **所需资源**：释义库 LLM 离线生成（无评测期调用）；句嵌入 1 GPU 日；1 人周工程。
- **落地步骤**：①32 任务程序库；②释义库 + 硬负例；③路由原型 + 32 路混淆矩阵；④训练增强 + 对比损失；⑤L0：标称不伤、释义稳、硬负例可分；⑥与 I9/I4/I6 联调。
- **风险**：评测指令若与训练标注逐字相同，路由收益退化为「安全网」（低风险低回报，可接受）；若评测指令为泛化模板，路由信息不足（转视觉任务分类，且需额外验证）；释义库覆盖不足导致 OOV（置信度门控 + 回退）；离线 LLM 生成质量（人工抽检 10%）。

    # min-max：最大化最坏语义边界，而非最小化平均 MSE（PR6）

        score = min(margin(cfg), 1.0 - d_disc(cfg))
        best = max(best, (score, cfg))

    L = latency_p99(model_q)
