# 第 66 轮（承接第 65 轮「VISTA 视觉知情安全时序归因」IP-214~223；新灵感循环第 1 轮；本轮灵感：「并发推理」×「推理延迟」）

> 第 65 轮把「几何可证伪」升级为「故障可归因」，其最大风险 A88 是：故障被假设为有限已知集合，且视觉与几何独立失效；未知复合故障会被硬归因、只膨胀错误的球，系统因「已经归因」而更自信。**把这条风险再往上追一层，会看到一个更朴素、也更致命的前提：VISTA 默认「语义流总能在实时流需要它之前算完，且算完的结论对执行时刻仍然成立」。这个前提把推理当成瞬时、免费、无抖动的函数。真实系统里，世界模型、FIR、AFA、CSP、AIC 都有延迟与尾部抖动；等你算清楚，你算的是过去的状态，而执行器已经走到了未来。** 本轮不问「谁坏了」，而问：
>
> **等我们搞清楚时，还来得及吗？一张证书的正确性，是否包含它到达的时刻？**
>
> 核心命题：**把安全从「算得对的证书」升级为「在截止期前到达、且对当前可达状态仍有效的证书」：用并发推理把归因/认证从串行改为可抢占的任意时组合，用 anytime-valid 证据替代固定样本后验，用延迟弹性前缀把推理时延变成显式安全预算，并把「证书生产速率 ≥ 执行消耗速率」作为一等可行性约束；时延本身成为可观测的故障通道。**

## 0. 直觉与动机

**灵感 1（并发推理 → 从「串行想清楚再做」到「边竞速边认证」）**
直觉：VISTA 的语义流像一个先把所有问题想完再开口的顾问：世界模型预测、阶段切分、故障归因、探针选择、块规划、认证前缀，一串做完才交给实时流。可机器人不能等顾问想完。并发推理提供另一种结构：在同一次观测的不可变快照上，同时跑多个「假设 / 保真度 / 动作块 / 投机猜测」分支，谁先给出足够紧且安全的界谁先赢，其余立即剪枝或取消。关键不是「把同样的计算并行化」，而是**改变决策对象**：从「等唯一正确答案」变成「在截止期内找到第一个可被证明安全的答案」。但必须诚实：并发不是免费的正确性；如果分支共享同一份错误模型，它们会一起错，竞速还会系统性奖励「算得最快」而非「算得最谨慎」的分支。

**灵感 2（并发推理 → 证书流水线：执行与下一张证书重叠）**
直觉：执行 k* 步需要 k*·Δt，下一张证书需要 L_cert 才能算完。若 L_cert ≥ k*·Δt，就会出现「证书空窗」：机器人正在执行一张已经过期、对当前状态不再有效的证书。并发可以把「执行当前前缀」和「计算下一张证书」重叠起来（双缓冲/软件流水线），形成证书的流水线；但前提是两张证书落在同一个可达漏斗内，且都不越过不可逆视界。于是系统吞吐不再由单次推理的墙钟时间决定，而由**证书生产速率是否追得上执行消耗速率**决定。这把「实时性」从一个性能 KPI 提升为一条安全可行性不等式。

**灵感 3（推理延迟 → 时延是安全预算，不是开销）**
直觉：第 65 轮把延迟当性能指标（≤2.5ms）。但时延直接吃掉停止距离与不可逆视界：推理慢一个控制周期，能安全执行的 k* 就要缩短。更根本地，**时延本身是状态**：尾延迟升高说明算力争用、模型病态或通信拥塞，而这恰恰是语义流结论不可信的信号；一个「很慢但很集中」的后验，可能只是延迟造成的假集中。延迟必须同时作为显式预算（缩短前缀）与显式证据（H_latency），而不是事后抱怨的日志字段。

**灵感 4（延迟 → 时机即正确性：too late is wrong）**
直觉：证书不是二值命题，而是**时空命题**。同一张证书，早到是安全资产，晚到是有害负债；同一张证书，覆盖状态集 A 时有效，覆盖状态集 B 时可能已经失效。KAIROS 把证书从「结论」改为四元组「（结论，覆盖的状态集，到达时刻，有效期 TTL）」，只有当前可达集被覆盖且未过期才允许派发。这把正确性从静态逻辑扩展为**时序正确性**：迟到的真话和早到的假话一样危险。

**灵感 5（合流 → KAIROS：Kairos-aware Concurrent Anytime Inference with Latency-Elastic Safe prefix）**
直觉：Kairos 是「恰当的时机」。安全不是「知道得最多」，而是「在正确的时刻知道得足够多」。闭环：LIC 延迟/信息契约 → CIP 并发组合（不可变快照、抢占、取消、线性化提交）→ AEC 任意时证据 → RES 竞速调度 → MFC 多保真级联 → CSC-K 延迟弹性认证前缀 → SAC 投机归因/提交 → TSB 尾延迟与陈旧度熔断 → RSC-K/WCV-K/CSP-K/AIC-K → J_kairos。VISTA 是「先算清楚，再执行」；KAIROS 是「**在时间的预算内，让足够安全的那部分先到**」。

**灵感 6（VISTA 组件的原位升级）**
- **FIR → FIR-K**：固定 n 的 Fisher/Laplace 后验 → anytime e-process/置信序列；任意调度、早停、取消都不破坏覆盖；故障集增 H_latency。
- **AFA → AFA-K**：探针价值从「互信息」改为「在剩余截止期内的期望互信息」；算不完的探针不做，探针也要赶 deadline。
- **CSC → CSC-K**：认证前缀计入尾延迟与停止延迟，k*_D 随延迟收缩；k*_D<1 立即转 Tier-0。
- **VPG/ACH → VPG-C/ACH-P**：视觉预测与动作块不再串行，改为多保真、可取消的并发组合；粗筛先行、精算后至。
- **RSC-V → RSC-K**：不确定球随陈旧度增长，r(τ)=r0+κ_τ·τ；只膨胀被归因者，但允许整体随时间老化。
- **WCV-V → WCV-K**：搜索域用延迟补偿后的可达集 B(φ̂_{t+τ}, r(τ))，证书只覆盖这段可达集。
- **CSP-V → CSP-K**：技能边带延迟预算；插入 reobserve / hold / slow_down / renew_certificate 元技能。
- **AIC-V → AIC-K**：干扰集增算力饥饿、优先级反转、延迟注入、快照撕裂、取消副作用、竞速偏差。
- **J_vista → J_kairos**：证书增 deadline、arrival、staleness、anytime coverage、pipeline utilization、speculation hit、scheduler trace。

## 1. 形式化定义（增量：定义 233–248）

- **定义 233（KAIROS 闭环）**：KAIROS=(VISTA, LIC, CIP, AEC, RES, MFC, CSC-K, SAC, TSB, RSC-K, WCV-K, CSP-K, AIC-K, J_kairos)。不变式：**任何被派发的动作必须被一张「在派发前到达、覆盖当前可达集、且未超过 TTL」的证书覆盖；并发分支只读不可变快照；提交是单一线性化点；Tier-0 降级不是错误而是安全状态。**
- **定义 234（延迟契约与陈旧度）**：控制周期 Δt；端到端证书延迟 L_cert、紧急停止延迟 L_stop（含检测、通信、制动，**不含**语义流重算）；尾部分位数 L^(p) 取 p=0.999。观测年龄 τ_obs=t_dispatch−t_obs。契约要求 τ_obs≤τ_max。deadline miss 与 stale snapshot 是显式事件，不能静默重试。
- **定义 235（不可变快照与并发组合）**：语义流对观测打版本 S_t=(ver, y_t, x′_t, ρ_{1:t})；所有并发分支只读 S_t；分支结果带 ver，ver 不一致即作废。动作先写 staging 缓冲，提交时原子地成为派发队列；取消分支不得有执行侧副作用。
- **定义 236（任意时证据与任意时安全裕度）**：对每个 H 与步 s，把「在 H 下第 s 步不安全」记为原假设 N_{H,s}: m_H(s)<0。用 e-process E_{H,s}(n)=∏_{i≤n}(q_i/p_mix(ρ_i)) 作为对 N_{H,s} 的证据，满足对任意停时 τ 有 E_{P_N}[E_{H,s}(τ)]≤1；等价地，直接维护安全裕度的时间一致置信序列 \underline m_H(s,n)，满足 P(∀n,∀s≤K: \underline m_H(s,n)≤m_H(s))≥1−α_any。只有当所有 H 与 s≤k 都满足 \underline m_H(s,n)≥0 时才认证前缀。**与固定 n 的 Fisher/Laplace 不同，该保证对任意由调度器决定的停时 n 成立**，因此竞速、早停、取消都不会破坏覆盖。
- **定义 237（竞速调度与剪枝）**：任务 i=(f_i,c_i,v_i)，f 保真度、c 算力/时延成本、v 期望风险降低。选择 a*=argmax_i v_i/c_i，s.t. Σc≤D−reserve；当某分支的风险上界被另一分支支配（UCB_i<LCB_j 且对决策不再有影响）即剪枝。调度决策只依赖已发生的信息（F_t 可测），因此不破坏定义 236 的任意时覆盖。
- **定义 238（多保真级联）**：保真度阶梯 f0≺f1≺f2；若 f0 的证书足够紧（安全裕度下界≥0 且与精算上界的间隙≤ε_tight）则早退，否则升级；总延迟 L_cert=Σ L_fi，期望延迟由「不升级概率」决定。级联把「精度」换成「确定性时限」。
- **定义 239（延迟弹性认证前缀）**：设 T_k=k·Δt。证书流水线无空窗要求 T_k≥L_cert；不可逆约束要求 T_k+L_stop≤m（m 为不可逆时界）。故可行前缀区间为 k∈[⌈L_cert/Δt⌉, ⌊(m−L_stop)/Δt⌋]；若区间为空，**不存在既不过期又不越界的正前缀**，必须转 Tier-0。取 k*_D=min(H, ⌊(m−L_stop)/Δt⌋)（在下界满足时），延迟越大、k*_D 越小。
- **定义 240（证书流水线与利用率）**：证书利用率 ρ_cert=L_cert/T_{k*_D}；ρ_cert≤1 才能背靠背无缝执行。双缓冲（执行前缀 i 时并发算 i+1）把串行气泡 L_cert+T_k 压到 max(L_cert,T_k)，但**不能取消 L_cert>T_k 时的空窗**；此时只能 hold/reobserve，或证明区间为空后转 Tier-0。双缓冲要求两张前缀在可达集上拼成漏斗（重叠裕度 κ_pipe）。
- **定义 241（投机归因与提交）**：由先验/上一轮后验猜 Ĥ，优先并发计算 C(Ĥ)；若验证分支在截止期前确认 Ĥ，则提交其证书；若竞速赢家与 Ĥ 不同或验证未完成，则丢弃预计算（零副作用），退回保守包络。定义投机命中率、投机浪费算力与延迟收益。
- **定义 242（陈旧度不确定性与延迟补偿可达集）**：r(τ)=r0+κ_τ·τ；WCV-K 的搜索域用 φ̂_{t+τ} 与 r(τ) 编译，证书覆盖 [t,t+τ_max] 内的可达集；τ>τ_max 时证书自动失效。
- **定义 243（时延作为故障证据与混杂控制）**：ℋ 增 H_latency（算力争用/模型病态/通信拥塞）。定义延迟膨胀比 ρ_lat=L^(0.999)/L^(0.5) 与陈旧超限率；当 ρ_lat>ρ̄ 或 τ_obs>τ_max 时，ρ 签名先做延迟归一化（条件化在 L、τ 上），**不得在未归一化时把「慢」误归因为 H_geo/H_force/H_policy**。H_latency 的处置是降保真度、缩 H、取消慢分支、提高 reserve。
- **定义 244（Tier-0 降级）**：若无证书在 D 前到达、或 τ_obs>τ_max、或可行前缀区间为空，则进入 Tier-0：hold/柔顺退让/safe_idle，最多维持有界 wrench；记录 deadline_miss、stale 与 blocking_task。Tier-0 必须可在无新推理的条件下由实时流独立执行。
- **定义 245（CSP-K 延迟感知技能规划）**：技能边带延迟预算 b_σ 与最大陈旧度；规划代价增 λ_L·E[L_cert] 与 λ_0·P(Tier-0)。技能图可插入 reobserve、hold、slow_down、renew_certificate、visual_probe；块边需 Valid(J_kairos) 且 k*_D≥1。
- **定义 246（AIC-K 对抗时延认证）**：ℰ_K=ℰ_V×ℰ_lat×ℰ_race×ℰ_tear；ℰ_lat 含算力饥饿、优先级反转、延迟注入、时钟漂移；ℰ_race 含竞速偏差（最快分支最不谨慎）、投机劫持；ℰ_tear 含快照撕裂、取消副作用、版本错配。n_cert 增加，ρ_dir 用对抗尾延迟而非经验均值。
- **定义 247（KAIROS 证书 J_kairos）**：J_kairos=(J_vista, deadline D, arrival t_arr, staleness τ_obs, anytime_coverage, L_cert^(0.999), ρ_cert, k*_D, speculation_hit, Tier-0 flag, scheduler_trace_hash, aic_k_ver)。Valid ⇔ Valid(J_vista) ∧ t_arr+TTL≥t_dispatch ∧ t_arr≤D ∧ τ_obs≤τ_max ∧ 覆盖≥1−α_any ∧ k*_D≥1（或 Tier-0 已安全接管）。
- **定义 248（KAIROS 算子）**：语义流 [快照→LIC 预算分配→CIP 并发分支（VPG-C/ACH-P/FIR-K/AFA-K/CSP-K/CSC-K）→RES 竞速与剪枝→AEC 任意时界→SAC 提交候选]；实时流 [读快照 ver→τ/L 检查→Tier-0 判定→CSC-K 前缀/双缓冲→staged 派发→到达时刻与陈旧度监控→TSB 熔断]。提交点是唯一的语义/实时交界。

## 2. 关键算法骨架

```python
# CIP + RES：截止期内的并发竞速（语义流）
snap = snapshot(obs)                         # 不可变、带版本
branches = spawn([
    vpg_c.predict(snap, fidel=0),           # 粗筛，<0.2ms
    fir_k.anytime(snap, HYP),               # e-process 增量更新
    ach_p.propose(snap, H),                 # 动作块组合
    sac.speculate(prev_post),               # 投机最可能假设
])
while time_left(D - reserve) > 0 and not cert_ready(branches):
    b = res.pick(branches, value_per_cost)  # 风险降低/单位时间
    b.advance(quantum)                       # 可抢占
    res.prune_dominated(branches)            # UCB 支配即剪枝
    if mfc.tight_enough(b): break            # 多保真早退
post, lower = aec.commit(branches, snap.ver) # 任意时有效

# CSC-K：延迟弹性前缀 + 双缓冲 + Tier-0
lo = ceil(L_cert_p999 / dt)
hi = floor((m - L_stop_p999) / dt)
if lo > hi or lower < 0:
    tier0_safe_idle(); return                # 无可行的正前缀
k_star = min(H, hi)
A = policy.prefix(k_star)
if L_cert_p999 > k_star * dt:
    hold(L_cert_p999 - k_star * dt)          # 双缓冲不能消除空窗
else:
    next_A = async_compute_next_prefix(snap) # 重叠执行，消除串行气泡
dispatch_staged(A[:k_star]); monitor_arrival()
```

## 3. 保证概要与推导要点

- **引理 9（任意时有效性）**：由 e-process 反演的 anytime 裕度下界，在任意由调度器选择的停时下仍满足 ≥1−α_any；固定样本的 Fisher/Laplace 后验在早停/竞速时没有时间一致覆盖。这直接修补第 65 轮未审计的统计前提。
- **引理 10（延迟弹性前缀）**：T_k≥L_cert 与 T_k+L_stop≤m 给出可行区间；区间为空则任何正前缀都不安全——时延吃掉的正是不可逆裕度。k*_D 对 L_stop 与 L_cert 单调不增。
- **引理 11（流水线-安全可行性）**：背靠背无缝执行等价于 L_cert≤T_k≤m−L_stop，即 L_cert+L_stop≤m；双缓冲只把吞吐从 L_cert+T_k 改善到 max(L_cert,T_k)，不改变可行性上界。
- **定理 9（KAIROS 端到端）**：在 A94–A100 下，凡被派发的动作都被「及时到达、覆盖当前可达集、anytime 有效、且 k*_D 可行」的证书覆盖；否则进入 Tier-0。安全从静态属性变为截止期属性。
- **定理 10（并发安全中性）**：在不可变快照 + staging + 原子提交下，取消/剪枝/投机失败的分支不改变派发动作，只消耗算力；竞速影响延迟，不改变语义。
- **命题（延迟-反应性权衡）**：固定 k*（第 65 轮）在 L_stop^(0.999)>0 时以正概率越过不可逆点；CSC-K 用 k*_D 恢复安全，代价是可推进步数减少、单位时间进度下降。
- **时延混杂**：未归一化的「慢」会伪装成「不确定」，H_latency 与延迟归一化是防止误归因的必要条件；AIC-K 用对抗尾延迟而非经验均值做认证。
- **实时性**：实时流只做快照读、τ/L 检查、Tier-0、前缀派发与到达监控（目标 <1ms）；并发、调度、世界模型全在语义流。

## 5. 本轮最大风险

**一句话**：KAIROS 把安全重新定义为「在截止期前到达的证书」，却依赖「系统能观测并强制执行自己的延迟」这一自指假设；在算力争用/尾延迟下，看门狗与推理共享同一基质，可能用一张自认为新鲜、实际已过期的证书放行，而竞速会系统性奖励「算得最快」而非「算得最谨慎」的分支——**时延从被管理的开销变成选择压力，制度性地奖励过早自信**。

## 2. 形式化定义（完整版）

**定义 233（KAIROS 闭环）** KAIROS 是 VISTA 的「时限-并发」升级：在 VISTA 的「语义流 ∘ 实时流」骨架上挂载 LIC（延迟/信息契约）、CIP（并发推理组合）、AEC（任意时证据）、RES（竞速调度）、MFC（多保真级联）、CSC-K（延迟弹性认证前缀）、SAC（投机归因/提交）、TSB（尾延迟与陈旧度熔断），并原位升级 RSC-V→RSC-K、WCV-V→WCV-K、CSP-V→CSP-K、AIC-V→AIC-K、J_vista→J_kairos。不变式：**(i) 任何被派发的动作必须被一张在派发前到达、覆盖当前可达集、且未超过 TTL 的证书覆盖；(ii) 并发分支只读不可变快照，结果按版本校验；(iii) 提交是唯一线性化点，取消分支不得有执行侧副作用；(iv) Tier-0 降级是安全状态而非错误重试。**

**定义 234（延迟契约与陈旧度）** 控制周期 Δt，证书截止期 D。定义端到端证书延迟 L_cert（从快照到证书可用）、紧急停止延迟 L_stop（从发现越界到执行器停止，含检测、通信、制动；**不含**语义流重算，因为 Tier-0 停止不依赖新推理）。取尾部分位数 L^(p)、p=0.999。观测年龄
τ_obs = t_dispatch − t_obs。
契约要求 τ_obs≤τ_max、t_arr≤D、t_arr+TTL≥t_dispatch。deadline miss 与 stale snapshot 必须显式记录并触发 TSB/Tier-0，不能静默重试或无限等待。

**定义 235（不可变快照与并发组合）** 语义流对每次观测生成版本化快照
S_t=(ver, y_t, x′_t, ρ_{1:t})，
所有并发分支只读 S_t。分支结果携带产生它的 ver，提交前校验 ver 一致；不一致即作废（快照撕裂检测）。动作先写 staging 缓冲；提交时以单一原子操作成为派发队列（线性化点）。被取消/剪枝/支配的分支不得对执行器、共享缓存或下一轮快照产生副作用。并发只允许改变「何时得到答案」，不允许改变「答案是什么」。

**定义 236（任意时证据与任意时安全裕度）** 对每个故障假设 H 与步 s，把「在 H 下第 s 步不安全」记为原假设
N_{H,s}: m_H(s)<0。
用 e-process
E_{H,s}(n)=∏_{i≤n} q_i / p_mix(ρ_i)
作为对 N_{H,s} 的证据，构造上满足对任意停时 τ 有 E_{P_N}[E_{H,s}(τ)]≤1。等价地（工程实现更直接），维护安全裕度的时间一致置信序列
\underline m_H(s,n)，使 P(∀n,∀s≤K: \underline m_H(s,n)≤m_H(s)) ≥ 1−α_any。
只有当 ∀H、∀s≤k 都有 \underline m_H(s,n)≥0 时，前缀 k 才被认证。**关键差别**：第 65 轮的 Fisher/Laplace 后验要求 n 固定；当 n 由竞速、早停或截止期决定时，固定样本保证失效。任意时保证对 F_t 可测的任意停时成立，故调度器「边算边停」不破坏覆盖。

**定义 237（竞速调度与剪枝）** 并发任务 i=(f_i,c_i,v_i)，f 为保真度、c 为算力/时延成本、v 为期望风险降低（可用当前裕度区间宽度与后验质量估计）。调度器在剩余预算 D−reserve 内选择
a* = argmax_i v_i/c_i，
按时间片抢占；当分支 i 被另一分支 j 在决策相关量上支配（UCB_i<LCB_j，且 i 不再影响任何可行决策）即剪枝。调度决策只能依赖已实现的历史（F_t 可测），因此定义 236 的任意时覆盖在「调度诱导的停时」上仍然成立。

**定义 238（多保真级联）** 保真度阶梯 f0≺f1≺f2（例如：线性化安全裕度 → 高斯过程/集合模型 → 完整世界模型 rollout）。若在最粗层已满足
\underline m_H^{(f0)}(s,n)≥0 且 gap( \underline m^{(f0)}, \overline m^{(f2)} )≤ε_tight，
则早退；否则升级到下一层。总延迟 L_cert=Σ_{已执行层} L_{f_i}。级联把「精度」换成「确定性时限」：用可证明的松界先挡住明显不安全，把精算留给真正接近边界的情形。

**定义 239（延迟弹性认证前缀）** 设 T_k=k·Δt。
- 无空窗（下一张证书须在前缀耗尽前到达）：T_k ≥ L_cert；
- 不可逆（故障在块首发生时仍能停住）：T_k + L_stop ≤ m。
故可行前缀集合为
k ∈ [ ⌈L_cert/Δt⌉ , ⌊(m−L_stop)/Δt⌋ ]。
若下界>上界，则**不存在既不过期又不越界的正前缀**，必须 Tier-0。否则取
k*_D = min(H, ⌊(m−L_stop)/Δt⌋)（并验证 ≥⌈L_cert/Δt⌉）。
k*_D 对 L_cert、L_stop 单调不增：**推理越慢，能安全承诺的步数越少**。第 65 轮的 k* 是 L=0 的特例。

**定义 240（证书流水线与利用率）** 证书利用率
ρ_cert = L_cert / T_{k*_D}。
ρ_cert≤1 时可背靠背无缝执行；ρ_cert>1 时必然出现长度为 L_cert−T_k 的证书空窗。双缓冲（执行前缀 i 的同时并发计算 i+1）把「串行气泡」从 L_cert+T_k 降为 max(L_cert,T_k)，但**不能取消空窗**：若 L_cert>T_k，执行完当前前缀后仍无新证书，只能 hold/reobserve；若可行区间为空，则只能 Tier-0。双缓冲要求相邻前缀在同一可达漏斗内拼接，定义重叠裕度 κ_pipe：两张前缀的并集仍须满足定义 242 的 r(τ) 与 m 约束。

**定义 241（投机归因与提交）** 由先验或上一轮后验猜测最可能故障 Ĥ，优先在专用分支上并发计算其证书 C(Ĥ)（例如对应 r_force 膨胀的保守包络）。若验证分支在截止期前确认 Ĥ，则提交 C(Ĥ)；若竞速赢家与 Ĥ 不一致、或验证未在 D 前完成，则丢弃预计算并退回不依赖 Ĥ 的保守包络。投机只写 staging，**丢弃必须零副作用**。定义投机命中率 h_spec=P(验证确认 Ĥ)、投机浪费算力 W_spec、延迟收益 ΔL_spec；若 h_spec 低而 W_spec 高，RES 自动降低投机优先级。

**定义 242（陈旧度不确定性与延迟补偿可达集）** 不确定半径随观测年龄增长：
r(τ)=r0+κ_τ·τ，κ_τ≥0。
WCV-K 用延迟补偿后的状态 φ̂_{t+τ} 与 r(τ) 编译搜索域：
B(φ̂_{t+τ}, r(τ)) ∩ 𝒢(g) ∩ K(μ̂) ∩ ℱ(f_lim) ∩ 𝒱 ∩ ℛ(τ_max)，
其中 ℛ(τ_max) 是 [t,t+τ_max] 内的可达集。证书只对该可达集负责；τ_obs>τ_max 时证书自动失效。这把「执行时状态已经和观测时不同」从隐含误差变成显式覆盖条件。

**定义 243（时延作为故障证据与混杂控制）** 故障集增
H_latency（算力争用 / 模型病态 / 通信拥塞 / 调度饥饿）。
定义延迟膨胀比 ρ_lat=L^(0.999)/L^(0.5) 与陈旧超限率。当 ρ_lat>ρ̄ 或 τ_obs>τ_max 时，阶段签名 ρ 先做延迟归一化（条件化在 L、τ 上再计似然）；**未归一化时不得把「慢」误归因为 H_geo/H_force/H_policy**，因为滞后残差会伪装成几何/模型不匹配。H_latency 的定向处置：降保真度、缩 H、取消慢分支、提高 reserve、插入 reobserve；而不是膨胀几何球。

**定义 244（Tier-0 降级）** 若 (i) 无证书在 D 前到达，(ii) τ_obs>τ_max，(iii) 定义 239 的可行区间为空，或 (iv) TSB 熔断，则进入 Tier-0：hold / 柔顺退让 / safe_idle，最多维持有界 wrench。Tier-0 必须能在**不依赖任何新推理**的条件下由实时流独立执行，并记录 deadline_miss、stale、blocking_task、last_valid_cert。Tier-0 不是失败，而是「在时间预算内无法证明安全」时的正确输出。

**定义 245（CSP-K 延迟感知技能规划）** 技能边带延迟预算 b_σ 与最大陈旧度 τ_max(σ)；规划代价增
λ_L·E[L_cert(σ)] + λ_0·P(Tier-0(σ))。
技能图可插入 reobserve（刷新快照）、hold（等待证书）、slow_down（降低 v_max 以买回停止裕度）、renew_certificate（延长 TTL）、visual_probe（AFA-K 的非接触探针）。块边需 Valid(J_kairos) 且 k*_D≥1；若某技能在预算内无法认证，规划器优先选择「可被 Tier-0 安全接管」的路径。

**定义 246（AIC-K 对抗时延认证）** 干扰集
ℰ_K = ℰ_V × ℰ_lat × ℰ_race × ℰ_tear，
ℰ_lat 含算力饥饿、优先级反转、延迟注入、时钟漂移；ℰ_race 含竞速偏差（最快分支最不谨慎）、投机劫持；ℰ_tear 含快照撕裂、取消副作用、版本错配。n_cert 增加（128→160，其中 32 用于时延/竞速/撕裂）；ρ_dir 用**对抗尾延迟**而非经验均值计算；J_dir 增 latency_calib_ver、scheduler_ver、snapshot_ver。认证目标不是「延迟小」，而是「在对抗延迟下仍能正确进入 Tier-0 或不派发」。

**定义 247（KAIROS 证书 J_kairos）** 
J_kairos=(J_vista, D, t_arr, τ_obs, anytime_coverage, L_cert^(0.999), ρ_cert, k*_D, speculation_hit, Tier-0 flag, scheduler_trace_hash, aic_k_ver)。
验证规则：
Valid(J_kairos) ⇔ Valid(J_vista)
∧ t_arr ≤ D ∧ t_arr+TTL ≥ t_dispatch
∧ τ_obs ≤ τ_max
∧ anytime_coverage ≥ 1−α_any
∧ (k*_D≥1 ∨ Tier-0 已安全接管)
∧ snapshot_ver 与派发时版本一致
∧ aic_k_ver 为当前版本。

**定义 248（KAIROS 闭环算子）** 语义流：
[快照 S_t→LIC 预算分配→CIP 并发分支（VPG-C/ACH-P/FIR-K/AFA-K/CSP-K/CSC-K）→RES 竞速与剪枝→AEC 任意时界→SAC 提交候选]；

提交点（staging→dispatch）是语义流与实时流的唯一线性化交界；任何跨越该点的状态都必须带版本与时刻。

## 3. 关键算法伪代码

### IP-224/225/227 LIC + CIP + RES（语义流并发竞速）

```python
class LatencyContract:
    """每个组件的硬时限；reserve 是留给 Tier-0 的不可侵占预算。"""
    def __init__(self, D, reserve, tau_max, p=0.999):
        self.D, self.reserve, self.tau_max, self.p = D, reserve, tau_max, p

    def budget(self, now, t_start):
        return max(0.0, self.D - (now - t_start) - self.reserve)


class ConcurrentPortfolio:
    """不可变快照 + 版本化结果 + staging 原子提交。"""
    def __init__(self, lic):
        self.lic = lic

    def snapshot(self, obs):
        return Snapshot(ver=next_version(), **obs)   # 只读

    def run(self, snap, branches, scheduler):
        live = list(branches)
        while live and scheduler.budget_left() > 0:
            b = scheduler.pick(live)                  # argmax v/c
            b.advance(scheduler.quantum)              # 可抢占
            live = scheduler.prune_dominated(live)    # UCB 支配即剪枝
            if scheduler.early_exit(live):            # 多保真紧度
                break
        results = [b.result for b in live if b.done and b.ver == snap.ver]
        return self.commit(results, snap.ver)

    def commit(self, results, ver):
        if any(r.ver != ver for r in results):
            raise SnapshotTear()                      # 版本错配 → 作废
        return pick_best_valid(results)               # 单一线性化点
```

### IP-226 AEC（任意时证据与安全裕度）

```python
class AnytimeEvidence:
    """e-process 增量更新；任何停时下覆盖有效。"""
    def __init__(self, hyp, alpha_any, mix):
        self.hyp, self.alpha, self.mix = hyp, alpha_any, mix
        self.logE = {h: 0.0 for h in hyp}

    def update(self, rho):
        for h in self.hyp:
            self.logE[h] += np.log(self.lik[h](rho) + 1e-12) - np.log(self.mix(rho) + 1e-12)

    def safe_margin_lower(self, s, n, alpha=None):
        # 由 e-process / 时间一致置信序列反演的 anytime 下界
        return self.cs.lower(self.hyp, s, n, alpha or self.alpha)

    def certify(self, k, n):
        return all(self.safe_margin_lower(s, n) >= 0.0
                   for s in range(k) for _ in self.hyp)
```

### IP-229/230/231 CSC-K + SAC + TSB（实时流）

```python
class LatencyElasticPrefix:
    def __init__(self, dt, m, lic):
        self.dt, self.m, self.lic = dt, m, lic

    def feasible(self, L_cert, L_stop):
        lo = int(np.ceil(L_cert / self.dt))
        hi = int(np.floor((self.m - L_stop) / self.dt))
        return (lo, hi) if lo <= hi else None

    def k_star(self, L_cert, L_stop, H):
        span = self.feasible(L_cert, L_stop)
        if span is None:
            return 0                                  # → Tier-0
        lo, hi = span
        return max(0, min(H, hi))


def realtime_dispatch(M, snap, A, post, lower):
    Lc = M.lic.p999_cert_latency()
    Ls = M.lic.p999_stop_latency()
    k = M.csc_k.k_star(Lc, Ls, len(A))
    if k < 1 or lower < 0 or M.tsb.should_trip(snap):
        return M.tier0.hold_or_retreat(reason='deadline_or_stale')
    if Lc > k * M.dt:
        M.tier0.hold(Lc - k * M.dt)                  # 双缓冲不能消除空窗
    else:
        M.pipeline.prefetch_next(snap)               # 重叠计算下一张证书
    M.staging.commit(A[:k], ver=snap.ver)            # 原子线性化
    return M.staging.dispatch()
```

```python
def KAIROS_round(M, obs):
    snap = M.portfolio.snapshot(obs)                 # 不可变、带版本
    # ———— 语义流：并发竞速，截止期内产出候选证书 ————
    branches = M.cip.spawn(snap, M.branch_specs)     # VPG-C/FIR-K/ACH-P/SAC

    M.aec.update(snap.rho)
    if M.tsb.latency_inflated() or snap.age > M.lic.tau_max:
        post = M.fir_k.latency_normalize(post, snap) # 防「慢被误归因」
    # ———— 实时流：延迟弹性前缀 + Tier-0 ————
    A = M.policy.propose_chunk(snap, M.H)
    k = M.csc_k.k_star(M.lic.p999_cert_latency(),
                       M.lic.p999_stop_latency(), M.H)
    if k < 1 or lower < 0:
        M.tier0.safe_idle(); return build_j_kairos(M, snap, post, lower, 0, tier0=True)
    M.staging.commit(A[:k], ver=snap.ver)
    M.staging.dispatch()
    # ———— 写回（纯语义流） ————
    M.rsc_k.update(balls=M.balls, tau=snap.age, post=post)
    M.dir.update(sample_batch_from_history(32))
    M.aic_k.certify(snap, post, M.balls, adversarial_latency=True)
    return build_j_kairos(M, snap, post, lower, k, tier0=False)
```

## 4. 推导

**引理 9（任意时有效性）** 设调度器与停止时刻 τ 均为 F_t 可测（只依赖已发生的数据），且对每个 H、s 存在时间一致置信序列 \underline m_H(s,n) 满足
P(∀n,∀s≤K: \underline m_H(s,n)≤m_H(s)) ≥ 1−α_any。
则对任意由调度器决定的执行时机，凡 max_H 认证的前缀都满足：P(存在一步真实裕度<0 却被执行) ≤ α_any。证明：事件「执行了不安全步」蕴含「某 \underline m_H(s,n)>m_H(s)」，其概率被置信序列的联合覆盖界控制；F_t 可测性保证调度器不能「偷看」未来，故可选停时适用。对比：第 65 轮的 Laplace 后验协方差 ≈J_fi⁻¹ 只在固定 n 下成立；当 n 由竞速完成顺序决定时，后验集中度不可控——**并发/早停把一个统计问题变成了必须用 anytime 工具的问题**。∎

**引理 10（延迟弹性前缀的单调性）** 由定义 239，可行区间 [L_cert/Δt, (m−L_stop)/Δt]。上界对 L_stop 严格不增，下界对 L_cert 严格不减；故 k*_D 对 L_cert、L_stop 单调不增。区间存在当且仅当
L_cert + L_stop ≤ m。
若成立，取 k*_D=max{k: kΔt≤m−L_stop} 且 k*_D≥⌈L_cert/Δt⌉，则 T_{k*_D}≥L_cert（证书不会过期）且 T_{k*_D}+L_stop≤m（能停住）。若 L_cert+L_stop>m，任何正 k 都至少违反一条：短前缀会过期、长前缀会越界，故 Tier-0 是唯一安全选择。∎

**引理 11（流水线-安全可行性）** 背靠背执行要求每张新证书在前一张前缀耗尽前到达，即 T_k≥L_cert；同时要求可停住，即 T_k≤m−L_stop。二者交集非空 ⇔ L_cert+L_stop≤m。串行（算完再执行）的周期为 L_cert+T_k；双缓冲的周期为 max(L_cert,T_k)，故双缓冲降低平均周期但不放宽交集条件。特别地，当 L_cert>T_k 时，双缓冲后仍会出现 L_cert−T_k 的空窗——**流水线只能隐藏延迟，不能违背不可逆约束**。∎

**定理 9（KAIROS 端到端「截止期即安全」）** 在 A94–A100 下：
- A94：快照不可变、结果版本化、提交线性化、取消无副作用；
- A95：AEC 的 anytime 覆盖 ≥1−α_any；
- A96：P(L_cert>L_cert^(0.999))≤β_cert，P(L_stop>L_stop^(0.999))≤β_stop；
- A97：τ_obs≤τ_max 被实时流强制；
- A98：L_cert^(0.999)+L_stop^(0.999)≤m（可行区间非空，否则走 Tier-0）；
- A99：AIC-K 覆盖对抗时延/竞速/撕裂；
- A100：Tier-0 可在无新推理下独立安全执行。
则凡被派发的动作，都以概率 ≥1−(α_any+β_cert+β_stop+α_stale+α_tear) 被一张「及时到达、覆盖当前可达集、anytime 有效、且 k*_D 可行」的证书覆盖；否则系统进入 Tier-0。于是 VISTA 的静态安全链被扩展为**时限-安全链**：正确性 = 结论正确 ∧ 时刻正确 ∧ 覆盖正确。∎

**定理 10（并发安全中性）** 设快照不可变、分支结果带 ver、提交为单一原子操作、取消分支无执行侧副作用。则派发动作是 (S_t, 已提交分支集) 的纯函数；任何未提交/被取消/被剪枝的分支不进入该函数。故投机、竞速、抢占只改变「何时得到答案」与「算力如何分配」，不改变「答案是什么」。注意这是条件性结论：若分支共享可变缓存、或取消会写日志到执行路径、或提交非原子，则中性性失效——AIC-K 的 ℰ_tear 专门认证这些反例。∎

**命题（延迟-反应性权衡）** 第 65 轮用固定 k*（隐含 L=0）。若真实 L_stop 有尾部分布，则 T_{k*}+L_stop>m 的概率为 P(L_stop>m−T_{k*})，在重尾下不可忽略。CSC-K 取 k*_D=⌊(m−L_stop^(0.999))/Δt⌋，把该概率压到 ≤β_stop，但每块少执行 Δk=k*−k*_D 步，单位时间进度下降 Δk/k*。因此「提高反应性」与「提高安全率」不是免费的：**时延预算就是不可逆裕度的预算**。当 L_cert 也接近 m 时，Δk→k*，系统退化为 Tier-0 主导——这给出了「推理系统本身成为瓶颈」的定量预警。∎

**命题（时延混杂）** 设真实状态在 τ 内移动了 δ。则滞后残差 e_vis、e_force 含有与 δ 成正比的成分，而 FIR 若不以 τ 为条件，会把 δ 误判为 H_geo/H_model/H_policy。由于 δ 与 τ 相关且 τ 与负载相关，未归一化的归因在尾延迟时段会系统性偏移。H_latency 与延迟归一化把 τ 从「噪声」变成「协变量」，是归因正确的必要条件。∎

## 7. 已知风险

**一句话**：KAIROS 把安全重新定义为「在截止期前到达的证书」，却依赖「系统能观测并强制执行自己的延迟」这一自指假设；在算力争用/尾延迟下，看门狗与推理共享同一基质，可能用一张自认为新鲜、实际已过期的证书放行，而竞速会系统性奖励「算得最快」而非「算得最谨慎」的分支——**时延从被管理的开销变成选择压力，制度性地奖励过早自信**。

**次级风险与缓解**：
1. **自指延迟（最大风险）**：Tier-0 与 LIC 监控若与推理共享 CPU/内存带宽，过载时监控本身被延迟，deadline miss 可能发生在「检查之后、派发之前」。缓解：Tier-0 放到独立看门狗/硬件定时器；LIC 用单调时钟与硬件时间戳；派发前二次校验 t_arr（检查-使用间隙必须短于硬件可保证的窗口）。
2. **竞速选择偏差**：最快完成的分支往往是最粗糙/最乐观的分支，竞速会把「谨慎但慢」的正确分支剪掉。缓解：安全门与竞速解耦（先过 \underline m_H≥0 再谈快慢）；对高保真分支保留保底时间片；「最慢分支否决权」用于高风险假设；AIC-K 的 ℰ_race 显式建模。
3. **分支相关性伪多样性**：所有分支共享同一世界模型/同一快照/同一 GPU，模型错时它们一起错，竞速给出「一致的错误」。缓解：至少一个独立实现的保守临界（解析界/规则式安全包络）；跨模型族/跨硬件冗余；AIC-K 共因建模。
4. **延迟分布非平稳/对抗**：p99.9 经验分位数在负载突变时失真，基于尾分位数的可行性判断会过于乐观。缓解：在线极值理论/一致性预测更新尾界；e-process 监控延迟漂移；reserve 随漂移自适应。
5. **快照撕裂与取消副作用**：并发分支若共享可变缓存、或取消时写执行侧状态，会破坏定理 10 的中性性。缓解：不可变快照、结果版本化、staging 双缓冲、取消路径静态检查、ℰ_tear 认证。
6. **anytime 证据的模型误设**：e-process/置信序列的覆盖依赖似然/混合分布的正确性；模型误设时名义 α_any 名不副实。缓解：保守混合、split-conformal 校准、AIC-K 把模型误设纳入最坏情形。
7. **双缓冲的可达漏斗拼接**：两张前缀在边界处的可达集可能不连续，κ_pipe 估计过乐观会把空窗变成「看似无缝的越界」。缓解：显式交集验证、保守 κ_pipe、边界处强制 reobserve。
8. **投机浪费与优先级反转**：低命中投机长期占用高优先级算力，反而拉高关键路径延迟。缓解：投机预算上限、抢占、按 h_spec/W_spec 动态降级。
9. **时钟同步/漂移**：语义流与实时流若用不同时钟，t_arr、τ_obs、TTL 都可能错。缓解：单调时钟、硬件时间戳、版本化时间基准、ℰ_lat 时钟漂移认证。
10. **Tier-0 本身的适用域**：hold/柔顺退让并非在所有接触状态下都安全（例如已在滑动、或抓取物易碎）。缓解：为每个技能预认证 Tier-0 包络；Tier-0 不可用时退化为「不启动该技能」而非冒险。
