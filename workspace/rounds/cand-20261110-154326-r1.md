# 第 44 轮（新循环第 4 轮） · FM-Cert × Cert-Roadmap：把「具身智能大模型」与「技术路线图」提升为可验证的生命周期对象（四层架构 v9 + 证书生命周期平面）

> 承接第 43 轮 v20（Persona-Cert × Concurrent-Cert）。v20 自陈最大风险是「共形边际覆盖被欺骗 + 多用户契约求交为空」，但它仍压着两个更深、且从未被写进不变式的单点假设：**(H1) 语义/规划层是一个版本稳定、冻结的具身大模型**——于是证书被当成系统的**常量**；可真实的具身智能大模型（VLA / world model / 操作策略）在持续预训练、微调、蒸馏、量化、热更新，能力包络随版本漂移，"模型 v 的证书"到 v+1 很可能**静默失效**。**(H2) 整栈（IP-45…59）被摆成一张扁平清单**——没有时间、依赖、成熟度的语义；而「技术路线图」要求的是**分阶段、带门禁、可审计的能力累积**，扁平清单天然允许「能力膨胀」（宣称的能力超过证书实际支撑）。本轮灵感词「具身智能大模型」「技术路线图」恰好命中这两个假设：**具身智能大模型**迫使我们把证书从常量变成**模型的函数**（版本锁定 + 能力包络 + 回归闸）；**技术路线图**迫使我们把研究纲领本身变成**可认证的阶段化依赖 DAG**（门禁谓词 + 证书成熟度 + 关键路径）。二者耦合处（模型演进 × 路线图）是本轮真正的新问题：**每次模型更新都是一次路线图事件，会批量吊销证书、制造证书债、并把再认证推上关键路径。**

## 0. 直觉与动机

**灵感 1（具身智能大模型 → 「证书是模型的像，不是系统的常量」）**：直觉上，我们说「这台机器人在这个场景安全」时，实际隐含了「用这个模型权重、这个量化版本、这套提示/技能库」。一旦换了 VLA 主干或做了一次 LoRA 微调，旧证书就像用旧地图导航新城市。因此必须给每条证书打上**模型指纹**（版本哈希 + 量化 + 技能库 + 校准集），并承认存在**能力包络 K_v**：模型 v 在任务×条件下「有证书支撑」的区域。能力包络不是模型自报的能力，而是**测试+证书**测出来的边界；包络之外的动作一律降级为「无证不可用」。一句话：**证书随模型走，换模型就换证书纪元（epoch）**。

**灵感 2（技术路线图 → 「路线图不是愿望清单，是带门禁的证书依赖 DAG」）**：直觉上，研究计划总写「先做 A 再做 B，最后落地 C」，但没人证明「B 真的建立在 A 的证书之上」「C 的宣称真的被 B 的证书覆盖」。于是把路线图形式化为阶段 S_0..S_n，每阶段有**门禁谓词 G_k**、能力集、驻留证书集与依赖边；规定**门禁健全性**：进入 S_{k+1} 必须有 S_k 的证书为 G_k 作证，**禁止能力膨胀**。再引入类似 TRL 的**证书成熟度等级 CML 0–6**，把每个 IP 钉在成熟度坐标上，路线图的关键路径就是「再认证 + 门禁证据」的关键路径。一句话：**没有证书支撑的阶段晋升是空头支票**。

**灵感 3（耦合 → 共演化路线图：模型更新是一等路线图事件，再认证要排进关键路径）**：把模型更新算子 U: M_v→M_{v+1} 与路线图合并后，出现三个只有耦合才会暴露的新问题：**(a) 证书债**——更新后未重验的证书数量 D，债务会随更新频率超线性累积；**(b) 再认证吞吐成为硬约束**——更新节奏快于再认证能力时，路线图在纸面上 sound、在执行上不可行；**(c) 自证陷阱**——若能力包络由模型自己的评测产出，共演化退化为**自签证书**，整个体系被一个「会给自己打高分的模型」击穿。因此必须引入外部锚定（独立测试台 / 第三方校准集 / 影子证书），并把「再认证」显式建模为路线图上的**带容量约束的任务**。

**耦合升级**：ECE（共演化引擎）负责版本锁定、能力包络与回归闸；CRP（路线图规划器）负责阶段门禁、CML、关键路径与再认证排程；ERV（演进路线图验证器）用更新 fuzz + 门禁重放 + 债务审计找反例并回灌 CKB。四层架构由 v8 的「仿真-检索-边缘-人格-并发」飞轮，升级为 v9：**在原有四层之上加一个贯穿式的「证书生命周期平面 CLP」**，让版本、债、门禁、再认证吞吐成为所有层共享的一等状态。

## 1. 形式化定义（增量：定义 44–50）

**定义 44（具身大模型指纹与模型绑定证书）**：模型指纹 φ(M)=(主干哈希, 权重版本, 量化方案, 技能/提示库版本, 校准集 id)。证书 c 升级为 c=(φ, C, θ, ℓ, ρ)，其中 C 为证书域、ρ 为证据来源（自测/外部台/影子）。**绑定律**：证书 c 仅对指纹 φ(c) 的模型有效；部署模型 M' 满足 φ(M')≠φ(c) 时 c **默认作废**，除非通过定义 45 的保持证明。

**定义 45（能力包络与证书-模型共演化）**：模型 v 的能力包络 K_v = {(task, cond) : ∃ 证书 c, φ(c)=φ(M_v) ∧ (task,cond)∈C_c}。更新算子 U: M_v→M_{v+1} 产生**增量证据集** ΔE。**证书债** D(v)=|{c : φ(c)=φ(M_v), c 未在 v+1 重验}|。**保持证明**：若 ΔE 能证明 C_c 在 M_{v+1} 上仍成立（同一不变式、同一阈值、同一证据口径），则 c 可**结转**（carry-over），否则必须再认证。**共演化 sound 条件**：任何守卫决策只能引用 **当前部署指纹** 下 valid 或已持保持证明的证书；即 `usable(c, M) ⇔ φ(c)=φ(M) ∨ carryover_proven(c, M)`。

**定义 46（可认证技术路线图）**：路线图 R=(S_0..S_n, E, G, cap, certs)。S_k 为阶段，E⊆S×S 为依赖边（DAG），G_k 为门禁谓词，cap_k 为该阶段宣称能力集，certs_k 为驻留证书。**门禁健全性**：S_k→S_{k+1} 合法，仅当 (1) 所有前驱阶段的 G 已由证书作证；(2) `cap_{k+1} ⊆ ⋃_{c∈certs_{≤k}} C_c`（无能力膨胀）；(3) 债务 D 在预算内。**定理（路线图 soundness）**：若每步晋升都满足门禁健全性、且每次模型更新在债务预算内完成受影响证书的再认证/结转，则任意阶段 k 部署系统所宣称的 cap_k 都被当前指纹下的有效证书覆盖。

**定义 47（证书成熟度等级 CML）**：CML ∈ {0 机理, 1 单元, 2 仿真, 3 硬件在环, 4 受控现场, 5 现场统计, 6 全生命周期}。每个 IP/证书映射到 CML 区间；**晋升规则**：CML 只允许逐级晋升，且每级要求对应证据（如 3→4 需 HIL + 影子零违例）。路线图门禁 G_k 可写成对 CML 的下界约束 `min_{c∈certs_k} CML(c) ≥ m_k`。

**定义 48（再认证吞吐与关键路径）**：再认证任务 r 有工作量 w_r、可并行度、依赖；系统再认证容量 B_rc（每单位时间可完成的等效重验）。**可行性**：关键路径长度 L_cp ≤ 更新间隔 T_update；否则滞后 L_cp−T_update 累积为债务。**债务动态**：D_{t+1} ≥ D_t + λ_upd·N_cert − B_rc·Δt。**命题**：当 λ_upd·N_cert > B_rc 时，证书债无界增长，路线图必然出现「纸面 sound、执行滞后」的不可行态——故 B_rc 必须作为路线图的一等资源被规划。

**定义 49（演进感知租约与版本栅栏）**：在定义 41 的租约 ℓ=(m,τ,λ,κ) 上追加版本纪元 e=φ(M) 与单调计数器：ℓ'=(m,τ,λ,κ,e)。**版本栅栏**：`lease_valid(ℓ,t,M) ⇔ e=φ(M) ∧ m−λ(t−τ)≥θ`。**模型切换原子性**：模型切换必须以 epoch 栅栏原子生效——旧 epoch 租约同一时刻全部失效，禁止「新模型 + 旧租约」的混用窗口。

**定义 50（能力膨胀与自证检测）**：设宣称能力 cap_claim、证书覆盖 cap_prove。**膨胀度** infl = |cap_claim \ cap_prove| / |cap_claim|。**自证风险**：若证据来源 ρ 中自测占比 > β，则包络被自我高估的风险不可控。**检测器**：对每个阶段输出 (infl, self_ratio)，任一超阈即拒绝晋升。**注**：这条把 v20 的「共形边际覆盖被欺骗」从统计层问题，升级为**制度层**问题——证据来源必须可审计。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-60 EMBODIED-FM-COEVOLUTION-ENGINE（具身大模型共演化引擎 ECE）
1. **指纹与版本锁定**：为每个模型发布计算 φ(M)，证书系统只接受带 φ 的证书；部署侧维护当前 epoch。
2. **能力包络标定**：从「测试台 + 证书 + 外部影子」三源估计 K_v，显式标注包络边界与置信度，拒绝模型自报能力直接入包络。
3. **结转/再认证判定**：对更新 ΔE 做保持证明；不能证明的证书进入再认证队列，生成证书债台账 D。
4. **回归闸与原子切换**：模型切换前跑包络回归（新旧包络差 + 安全谓词回归 + 影子证书零违例），通过才 bump epoch，且 bump 是原子的（定义 49）。

### 2.2 IP-61 CERTIFIED-ROADMAP-PLANNER（可认证路线图规划器 CRP）
1. **路线图形式化**：把 IP-45…60、实验 E 系列、部署场景编译为阶段 DAG，门禁写成可判定的谓词。
2. **CML 台账**：每个 IP/证书标注成熟度与证据，检测「跳级宣称」（如仿真证据直接支撑现场发布）。
3. **关键路径与再认证排程**：以 L_cp 与 B_rc 做可行性分析，输出「按更新节奏应提前重验哪些证书」的排程；债务超预算即报警。
4. **能力膨胀检测**：每阶段输出 (infl, self_ratio)，红线拒绝晋升；生成补齐证书的最小计划。

### 2.3 IP-62 EVOLUTION-ROADMAP-VALIDATOR（演进路线图验证器 ERV）
1. **更新 fuzz**：注入权重扰动、量化切换、技能库增删、灾难性遗忘场景，检验版本栅栏与结转判定是否漏放。
2. **门禁重放**：对每个阶段做「证书→门禁→能力」的审计重放，检出无证晋升与能力膨胀。
3. **债务审计**：模拟不同更新节奏 vs 再认证容量，绘出债务相图，找不可行区间。
4. **自证对抗**：构造「自我高估」模型（在自测集上刷分、外部集掉分），验证 ECE 的包络标定与 ρ 检测能否挡住。

## 5. 本轮最大风险

**一句话**：能力包络 K_v 是整个共演化体系的**新单点真值**——若它主要来自模型自测或被更新回归「刷」出来，那么「版本锁定 + 路线图门禁」会把**自签证书**包装成看似严谨的依赖 DAG，且证书债在高更新节奏下超线性累积会让路线图「纸面 sound、执行不可行」——因此 E95（包络标定）与 E102（自证对抗）必须设为红线，默认回退到「冻结 epoch + 只信外部证据」的不可自证底线。

# 第 44 轮产物 · 创新点清单 v21：FM-Cert × Cert-Roadmap（ECE × CRP × ERV）× 可验证模型共演化与阶段化路线图（四层架构 v9 + CLP）

> 承接第 43 轮产物 v20。本轮**增量插入** IP-60/61/62，并升级 IP-44/45/47/49/50/51/52/53/54/55/56/57；不推倒任何既有层级。核心是把 v20 的「个性化并发闭环」升级为**生命周期闭环**：证书不再是系统常量，而是**模型指纹 φ 的函数**；研究纲领不再是扁平 IP 清单，而是**带门禁与成熟度的阶段 DAG**。一句话：**证书随模型走，路线图靠证书立。**

## 0. 核心 IP 设计

## 1. 符号体系（增量：定义 44–50 符号）

| 符号 | 含义 | 定义 |
|---|---|---|
| φ(M) | 模型指纹 | (主干哈希, 权重版本, 量化方案, 技能库版本, 校准集 id) |
| c=(φ,C,θ,ℓ,ρ) | 模型绑定证书 | 证书域 C 只对指纹 φ 的模型有效；ρ 为证据来源 |
| K_v | 能力包络 | 模型 v 有证书支撑的 (task, cond) 区域 |
| U: M_v→M_{v+1} | 更新算子 | 产生增量证据 ΔE |

## 2. 关键算法（伪代码）

### IP-60 ECE：指纹、包络、结转与债务
```
def fingerprint(model):
    return Hash(model.backbone, model.weights, model.quant,
                model.skill_lib, model.calib_set_id)

def usable(cert, model_now):
    # 定义 45：只认当前指纹 valid 或已持结转证明
    return cert.phi == fingerprint(model_now) or carryover_proven(cert, model_now)

def certify_under_envelope(action, model_now, K_v, guard):
    phi = fingerprint(model_now)
    if (action.task, action.cond) not in K_v:      # 包络外：无证不可用
        return downgrade(action)
    m = min(cert_lookup_L0(action).m_lo,
            lease_decay(action.lease),
            persona_cap(action.persona))
    return guard_ok(m, action.theta)

def on_model_update(old, new, cert_pool, budget_debt):
    phi_new = fingerprint(new)
    delta = regression_evidence(old, new)          # 外部台 + 影子，非纯自测
    debt = []
    for c in cert_pool:
        if carryover_proven(c, new):
            c.phi = phi_new                        # 合法结转
        else:
            debt.append(c)                         # 入再认证队列
    if len(debt) > budget_debt:
        raise RoadmapInfeasible(debt)              # 债务超预算：拒绝晋升/切换
    K_new = calibrate_envelope(new, external_only=True)
    return CertEpoch(phi_new, K_new, debt)

def atomic_switch(epoch, runtime):
    # 版本栅栏：切换瞬间旧 epoch 租约全部失效（定义 49）
    runtime.fence(epoch.phi); runtime.install(epoch)
```

### IP-61 CRP：门禁、CML、关键路径与能力膨胀
```
def gate_ok(stage, certs, cap_claim, m_k):
    proven = union_domains([c.domain for c in certs if usable(c, stage.model)])
    infl = size(cap_claim - proven) / max(1, size(cap_claim))
    if infl > INFL_MAX:                            # 无能力膨胀
        return False, Inflate(infl)
    if min(cml(c) for c in certs) < m_k:           # CML 下界
        return False, JumpCML()
    return True, Ok()

def critical_path(R, B_rc, T_update):
    L_cp = longest_path(R.dag, weight=lambda r: r.workload / parallelism(r))
    feasible = L_cp <= T_update * B_rc
    debt_growth = current_debt + updates_per_interval * n_cert - B_rc * T_update
    return L_cp, feasible, debt_growth

def schedule_recert(R, B_rc, updates):
    # 把再认证任务排在前驱门禁之前，输出最小补齐计划
    order = topo(R.dag)
    return list_scheduler(order, capacity=B_rc, deadlines=updates)
```

### IP-62 ERV：更新 fuzz、门禁重放与自证对抗
```
def update_fuzz(model, cert_pool, n):
    cases = [perturb_weights, switch_quant, add_skill, drop_skill,
             catastrophic_forget, partial_rollback]
    bad = []
    for _ in range(n):
        m2 = apply(random.choice(cases), model)
        for c in cert_pool:
            if usable(c, m2) and not invariant_holds(c, m2):
                bad.append((c, m2))                # 结转漏放
    return bad

def replay_gate(R, model_at_stage):
    for k in range(1, len(R.stages)):
        ok, why = gate_ok(R.stages[k], R.certs[k], R.cap[k], R.m[k])
        if not ok:
            return Violation(stage=k, reason=why)
    return Sound()

def self_proof_attack(K_v, rho):
    # 构造在自测集刷分、外部集掉分的模型，检验包络标定
    self_ratio = rho.self / max(1, rho.self + rho.external + rho.shadow)
    return self_ratio <= BETA and envelope_consistent(K_v)
```

## 5. 风险与缓解（增量）

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 能力包络由模型自测产出，自证导致整体 soundness 崩塌 | 高 | E95/E102 红线；外部台 + 影子三源；self_ratio 审计；自测证据不得单独支撑门禁 |
| 模型更新快于再认证容量，证书债超线性累积，路线图纸面 sound 执行不可行 | 高 | E97/E99 红线；B_rc 一等资源；L_cp≤T_update 门禁；债务超预算冻结更新 |

| 能力膨胀检测把「渐进能力」误判为膨胀，导致路线图过度保守 | 中 | 分阶段 cap 拆分 + 最小补齐计划；infl 阈值按 CML 分层 |

## 6. 本轮最大风险

**一句话**：能力包络 K_v 是整个共演化体系的**新单点真值**——若它主要来自模型自测或被更新回归「刷」出来，那么「版本锁定 + 路线图门禁」会把**自签证书**包装成看似严谨的依赖 DAG，且证书债在高更新节奏下超线性累积会让路线图「纸面 sound、执行不可行」——因此 E95（包络标定）与 E102（自证对抗）必须设为红线，默认回退到「冻结 epoch + 只信外部证据」的不可自证底线。
