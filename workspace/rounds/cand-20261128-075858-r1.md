### 第 6 轮灵感驱动研究记录（新循环·第 1 轮）

**灵感词**：协同控制、成功率

**继承关系**：第 5 轮 CADVS-v5（IP-493~496）以「认证的生成式执行」（CGE）把 v4 的七硬门从离散规则提议推广到任意生成器：条件流匹配提议 π_θ^FM、LMEM-v2 记忆固化、FAMK 情感调制、EFA-v5 级联选证；定理 5/6/7/8 保证阈值只紧、证书与提议无关、固化有界、七锚完备，执行集 Exec_CADVS-v5 ⊆ Exec_CADVS-v4 ⊆ … ⊆ Exec_v29。本轮不推翻 v5，而是回答 v5 完全没触及的两个问题：(a) 当执行主体从「单机器人」变成「必须协同的机器人联盟」时，认证的单位和组合规则是什么？(b) 现有框架只给「安全」的单侧收缩证书，从不回答「任务究竟能不能做成」——成功率能否也被认证，而不破坏安全？两个灵感词统一为主题「认证的协同成功率」（Certified Cooperative Success, CCS），形成 CADVS-v6（IP-497~500）。本轮自律：**七硬门一个不增**；新增的是「联合门提升 + 协同协议 + 成功率统计证书」三层，分别回答组合、进度、下界。执行集升级为 Exec_CADVS-v6 ⊆ Exec_CADVS-v5^⊗ ⊆ …。

**直觉与动机**：

1. **协同控制 → 认证单位从「单条轨迹」上移到「联盟联合执行」，而组合的危险全在接缝**。把协同想成一支手术团队：每个医生都持证，不代表同台手术安全——真正的风险是共享术野（共享工作空间）、共享病人（共享人类）、共享器械（共享资源）、以及「我以为你会让、你以为我会停」的假设错配。单机证书是**局部谓词**，多机安全是**联合谓词**，局部真值不能自动推出联合真值。因此引入**联盟契约** C_Coal=(V, A2G, R, κ, m, h, σ_emb, v)：V 为成员，A2G 为逐门的 assume-guarantee 对（每个成员在「邻居保证 G」的假设 A 下承诺 G），R 为共享资源预约（工作空间单元/时间窗/负载/人类注意力），其余继承 v5 能力契约。门不再逐机独立评估，而是**提升**到联合状态：kc_i^↑(x)=（∧_{j∈V} kc_i^j(x^j)）∧ cpl_i(x)，其中 cpl_i 是跨体耦合谓词（互碰、联合 ZMP、合成扳手、共享人类安全距离）。**定理 9（联合门提升的可靠性）**：若 A2G 闭环（每个成员的假设被邻居的保证覆盖）且 cpl_i 是真实耦合谓词的保守过近似，则提升门通过 ⇒ 联合安全；否则必须由协同协议强制闭环，不能默认成立。

2. **成功率 → 安全是「硬证书」，成功率是「统计下界证书」，两者必须分层而不能混用**。安全门是确定性的集合收缩，回答「不会出事」；成功率是概率性的覆盖问题，回答「多大概率做成」。用安全门去卡成功率，会把系统越调越保守、成功率塌成 0；用成功率去松安全门，则是拿安全换指标。正确做法是**双层证书**：底层仍是冻结的七硬门（Exec 集合，硬约束，永不为成功率让步）；上层是成功率证书 SR_LB——用可交换标定集上的 Clopper-Pearson/分裂共形下界给出「真实成功率 ≥ SR_LB 的概率 ≥ 1−δ」，并按上下文（任务类/团队规模/资源竞争度）做 Mondrian 条件化；分布漂移用在线自适应共形（ACI）维持长期覆盖率。成功率**只允许通过提议与协同在 Exec 内部提升**（更好的候选、更少的拒绝、更顺的协同），绝不允许通过降低阈值扩大 Exec。这正是 v5 定理 6（证书不变性）的延伸：提议可换、协同可加、门不可动。由此得到**定理 12（安全-成功率分离）**：固定门时，成功率的任何提升都来自 Exec 内的覆盖改善；若某机制靠放松门来提升成功率，则安全单调性被破坏，二者不可兼得。

3. **协同与成功率的交叉 → 多机成功率有「乘积诅咒」，协同的价值必须用可认证的增益来衡量**。若各机独立、单机成功率 s，则 n 机联合成功率 = s^n 指数衰减：2 机 0.9 尚有 0.81，6 机就跌到 0.53。**定理 10（协同成功率界与乘积诅咒）**给出无分布假设的双边界：SR_joint ≤ min_j SR_j（木桶上界，所有成员都得成功）且 SR_joint ≥ max(0, 1−Σ_j(1−SR_j))（联合界下界）；独立时精确等于乘积，同质时 s^n。协同（共享提议、联合预约、信息对齐）只能改变失败的相关结构，最大增益被 min_j SR_j − ∏_j SR_j 封顶。这把「协同」从口号变成可测的量：**协同增益 Δ_coord = SR_joint^coord − ∏_j SR_j^indep**，并直接引出「成功预算」——按目标成功率反推可接受的团队规模与构成。另一个交叉点是**通信陈旧**：协同证书会过期，陈旧的「对方会让」假设是致命错误。**引理 46（陈旧安全单调性）**：证书年龄↑ ⇒ 假设集合↑（更保守） ⇒ 门通过集↓，于是成功率下降但安全不破——stale-safe 回退用「成功率」换「安全」，方向永远正确。

**关键洞见**：v5 回答「单机、任意提议下如何守住安全边界」；v6 回答「多机协同、且要回答能不能做成时，如何同时给出硬安全证书与软成功率下界，并证明二者正交」。七原子门 kc_evidence_forged_v4 原样冻结；新增的只是：联合门提升算子 ↑_Coal（组合）、协同协议 CPK（进度/无死锁/新鲜度）、成功率证书 SRCK（统计下界）、软评分 ECS_v6 = ECS_v5 · η_succ。执行集 Exec_v6 ⊆ Exec_v5^⊗ 由「逐门提升保守 + A2G 闭环 + 证书新鲜」保证；成功率提升只发生在 Exec_v6 内部，故安全单调性与成功率单调性互不越界。七锚完备性、提议无关性、固化有界性全部继承。

**形式化目标（增量）**：
1. 联合状态与门提升：x=(x^1,…,x^n)∈∏_j S_j；kc_i^↑(x)=（∧_{j∈V} kc_i^j(x^j;τ_i^5)）∧ cpl_i(x;τ_i^5)；A2G 闭环条件 A_j ⊆ ∧_{k∈N(j)} G_k。
2. 协同协议 CPK=(预约 Res, 优先级序 ≺, 新鲜度 Fresh, 无死锁调度 Sched, stale-safe 回退)：共享资源预约 + 全序破环；证书年龄 a>τ_comm ⇒ 假设取「资源被占用」的最保守闭包。
3. 成功率事件 Succ(x)=1[任务在 T_budget 内完成 ∧ 无安全违例]；成功率证书 SR_LB = LCB_{1−δ}(Succ | context)，Mondrian 条件化 + ACI 漂移更新。
4. 定理 9（联合门提升可靠性）、定理 10（协同成功率界/乘积诅咒）、定理 11（成功率证书覆盖率与样本复杂度）、定理 12（安全-成功率分离）；引理 45（提升保守性）、46（陈旧安全单调）、47（LCB 样本复杂度）。
5. 成功感知级联：Exec_v6 内先用成功率头 q_ψ 排序，再取「认证边际 × 预测成功率」最大者；q_ψ 只做 tie-breaker，永不越过门。
6. Exec_CADVS-v6={x∈supp(π_fused): Conform(V) ∧ ∧_{i=1..7} kc_i^↑(x;τ^5)=1 ∧ Fresh(Cert) ∧ SR_LB(c)≥SR_target} ⊆ Exec_CADVS-v5^⊗。

**本轮最大风险**：**成功率证书的分布外失效与协同选择偏差**——统计下界只在「标定集与部署集可交换」时成立，而开放联盟的异质队友、通信陈旧和「按成功率挑策略/挑队友」的选择偏差会系统性高估真实成功率，且提升成功率的压力会持续侵蚀「安全-成功率分离」这条设计红线。

```python
class CoalitionContractGateLiftingKernel:
    """CCGK：把七原子门从分量状态提升到联合状态。
    定理 9：A2G 闭环 + cpl 保守过近似 ⇒ 提升门通过蕴含联合安全"""

    coupling: dict               # {gate_i: cpl_i}，必须 over-approximate 真耦合
    tau4: dict                   # v4 静态阈值，冻结只读

    def conform(self, contract, embodiment) -> bool:
        """准入一致性：动力学类/执行器限/传感集必须落在各门假设域内"""
        return all(embodiment.in_domain(gate.assumptions) for gate in GATES)

        for j in contract.V:
            for i, (A_ij, G_ij) in self.a2g.items_for(j):
                # 假设必须被所有邻居的保证覆盖
                if not subset(A_ij, meet(self.a2g.guarantee(k, i) for k in N(j))):
                    return False
        return True
```

### IP-498 CCPK：协同控制协议核（10–100 Hz，与控制环解耦）

```python
@dataclass
class CooperativeCoordinationProtocolKernel:
    """CCPK：资源预约 + 全序破环 + 新鲜度 stale-safe。
    红线：协同协议只决定「谁在何时用何资源」，绝不修改门谓词"""
    tau_comm: float = 0.10        # 证书新鲜度上限（秒）
    order: Callable = lambda j: j # 成员全序 ≺（缺省 ID 序）

    def reserve(self, x, R) -> Reservation | None:
        """按 ≺ 顺序申请共享资源；冲突则让位，不抢占高优先级"""
        held = {}
        for j in sorted(x.members, key=self.order):
            need = x.resource_demand(j)          # 工作空间单元×时间窗/负载/人类
            if conflicts(need, held, R):
                return None                      # 预约失败 → 保守回退
            held[j] = need
        return Reservation(held)

    def schedule(self, reservation) -> bool:
        """等待图无环：因 ≺ 为全序，只能低优先级等高优先级，
        故 wait-for 图必为 DAG（定理 9 推论：无死锁）"""
        ...

    def fresh(self, cert, t_now) -> bool:
        return (t_now - cert.t_cert) <= self.tau_comm and cert.sig_valid()

    def stale_safe_assumptions(self, certs) -> dict:
        """证书过期 ⇒ 假设闭包取「资源被占用/对方不让行」的最保守值。
        引理 46：年龄↑ ⇒ 假设集↑ ⇒ 门通过集↓（安全不破，成功率下降）"""
```

### IP-499 SRCK：成功率证书核（任务准入时域，秒级；离线标定）

```python
@dataclass
class SuccessRateCertificateKernel:
    """SRCK：成功率下界证书（统计层），与安全门（硬层）正交。
    定理 11：可交换标定 ⇒ 覆盖率 ≥ 1−δ；ACI 维持漂移下长期覆盖"""
    delta: float = 0.10           # 置信度参数
    buckets: Callable = context_key   # Mondrian 条件化：任务类/团队规模/竞争度
    aci_gamma: float = 0.02       # 在线自适应步长

    def calibrate(self, episodes) -> dict:
        """严格隔离：标定集不得与策略选择/固化训练集重叠（防选择偏差）"""
        stats = defaultdict(lambda: [0, 0])   # bucket -> [success, total]
        for ep in episodes:
            stats[self.buckets(ep.context)][1] += 1
            stats[self.buckets(ep.context)][0] += int(Succ(ep))
        return {b: clopper_pearson_lcb(k, n, self.delta / max(1, len(stats)))
                for b, (k, n) in stats.items()}   # Bonferroni 分桶

    def lower_bound(self, context) -> float | None:
        b = self.buckets(context)
        if self.cal[b][1] < self.n_min:
            return None                          # 标定不足 → 不签发（fail-closed）
        return self.cal[b]

    def admit(self, context, sr_target) -> bool:
        lb = self.lower_bound(context)
        return lb is not None and lb >= sr_target   # 无下界不冒充点估计

    def aci_update(self, err_t: float, alpha_t: float) -> float:
        """分布漂移：α_{t+1}=α_t+γ(α−err_t)，维持长期误覆盖率 ≈ α"""
        return alpha_t + self.aci_gamma * (self.delta - err_t)
```

## 4. 正确性论证（增量更新）

### 引理 45（联合门提升的保守性）

**陈述**：若 cpl_i 是真实跨体耦合谓词 cp_i^* 的过近似（cpl_i(x)=1 ⇒ cp_i^*(x)=1），则 kc_i^↑ 是「局部合取 ∧ 真实耦合」的过近似；当 cpl_i 精确且 A2G 闭环时提升门与真实联合门等价。∎

**工程含义**：提升的保守性完全由 cpl_i 的过近似质量决定；学习型 cpl 若欠近似，会引入「提升门通过但实际耦合违约」的漏放，必须由联合仿真/现实标定兜底（对应 R62）。

### 引理 46（陈旧证书的安全单调性）

**陈述**：设证书年龄 a 增大时假设闭包 A(a) 单调不减（越旧越保守），门通过集 Exec(a) 单调不增。则 a↑ ⇒ SR↓ 且安全违例率不增。**证明**：假设集↑ ⇒ 门谓词更难满足 ⇒ 通过集↓；成功率是 Exec 上 Succ 的概率，集合缩小只能降 SR；安全违例在 Exec 上恒 0，与 a 无关。∎

**工程含义**：stale-safe 的方向是「用成功率换安全」，绝不允许反向（陈旧时反而放宽假设），否则协同会因过期信息放大风险。

### 引理 47（成功率 LCB 的样本复杂度）

**陈述**：欲使 Clopper-Pearson 下界与真实 SR 的偏差 ≤ ε 且置信度 ≥ 1−δ，所需标定样本 n = O(ε^{−2} log(1/δ))（Hoeffding 型充分条件 n ≥ (2ε²)^{−1} ln(2/δ)）；Mondrian 分 B 桶时每桶用 δ/B 保证联合覆盖 ≥ 1−δ。**证明**：Hoeffding 不等式 + Bonferroni。∎

**诚实边界**：样本复杂度与 context 维度无关（只与桶数有关），但**桶内可交换性**无法由数据本身保证；高维 context 的分桶会稀疏化样本，导致「标定不足 → 拒绝签发 → 成功率准入长期不可用」。这是统计层固有的小样本代价。

### 定理 v6（协同安全与成功率双层证书，总装）

**陈述**：在 v5 假设 (B1)~(B7) 及新增 (B8) cpl_i 保守过近似、(B9) 标定集与部署集可交换（或 ACI 长期覆盖）下：

(i) **联合安全**：A2G 闭环 ∧ Conform(V) ∧ Fresh(Cert) ⇒ Exec_v6 ⊆ Exec_v5^⊗，且提升门通过蕴含联合安全（定理 9）；
(ii) **无死锁**：全序 ≺ + 不抢占 ⇒ 资源等待图无环（定理 9 推论）；
(iii) **成功率界**：SR_joint ≤ min_j SR_j 且 ≥ max(0,1−Σ(1−SR_j))；独立时 = ∏ SR_j（定理 10）；
(iv) **证书覆盖**：P(SR(c) ≥ SR_LB(c)) ≥ 1−δ（可交换）；标定不足不签发（定理 11）；
(v) **安全-成功率分离**：成功率提升只能发生在 Exec_v6 内（提议/协同/排序），放松门则破坏 (i)（定理 12）；
(vi) **陈旧单调**：a↑ ⇒ SR↓ 且安全不降（引理 46）。

**证明**：(i)(ii) 由定理 9；(iii) 由定理 10；(iv) 由定理 11+引理 47；(v) 由定理 12+定理 6；(vi) 由引理 46。∎

**诚实声明**：(B8) cpl 的欠近似无法被证书内证明发现，只能靠联合仿真/现实标定；(B9) 可交换性在开放联盟、异构队友、非平稳环境中经常不成立，ACI 只保证长期平均而非逐步；(iii) 的联合界在 n 大且 SR 中等时极松（下界趋 0），不能替代真实协同增益测量；(v) 只保护「安全不被成功率侵蚀」，不保证成功率证书本身为真（Goodhart 仍可能在统计层发生）。

| R68 | 联合状态/契约组合爆炸 | 中 | 稀疏邻接 + 分层分组 + 只提升相邻耦合；契约缓存 | 大规模联盟的可扩展性未验证 |

## 7. 本轮最大风险（最终确认）

**一句话**：**成功率证书的分布外失效与协同选择偏差**——统计下界只在「标定集与部署集可交换」时成立，而开放联盟的异质队友、通信陈旧，以及「按成功率挑策略/挑队友」的选择偏差，会系统性高估真实成功率；同时提升成功率的压力会持续侵蚀「安全-成功率分离」这条设计红线，使证书在形式上覆盖、实质上失真。
