# 第 67 轮（承接第 66 轮「RAS 情绪驱动闭环」IP-224~233；灵感循环第 1 轮；本轮灵感：「痛点分析」×「差异化定位」）

> 前 66 轮有一条隐含的「复杂度棘轮」：VISTA 用 6 类故障，RAS 扩到 7×4，LADDER 再加博弈维度。每一轮都声称「更安全」，但**安全从来不是均匀的**：一次灾难性漏放带来的痛，远大于十次保守降级；而验证预算、探针时间、算力、人类注意力都是固定的。于是「继续加维度」在预算约束下反而**稀释**了本该压在真痛点上的验证资源——这本身就是 VISTA/RAS 线最大的痛点。
>
> 本轮的核心命题是：
>
> **把「不断加维度的安全闭环」升级为「按痛点分诊的差异化认证」：用痛点泛函度量每种故障在具体部署语境下的期望代价，用未保险痛点密度（严重度 × 不确定性）把有限验证预算分配到「最疼且最不确定」的假设上，用灾难性置信地板兜底，用复杂度租金主动剪枝——TRIAGE（Tail-Risk-Informed Allocation of Guaranteed Effort，尾风险感知的分诊式保证投入）。**
>
> VISTA 问「哪层坏了」，RAS 问「谁控制、控制多少」，LADDER 问「谁配获得更多自主」；TRIAGE 问的是：**「哪一处疼、有多疼、下一份验证预算该压在哪里」**。

## 0. 直觉与动机

**灵感 1（痛点分析 → 安全不是均匀的）**
直觉：第 66 轮 RAS 把证书写成 `Valid ⇔ Valid(J_vista) ∧ λ_risk ≥ 0.6 ∧ …`，这是一个**严重度盲**的二值谓词：无论漏放的是「杯子没抓稳」还是「机械臂碰到人」，只要置信度达标就同等放行。但部署方的真实痛感是高度不对称的——假放行（false pass）与假降级（false downgrade）的代价比 `κ = ℓ_FP/ℓ_FD` 往往在 10 以上，且真正决定事故期望的是**尾部**而非均值。痛点分析的第一步，就是承认「安全预算必须按后果分诊」，而不是按假设个数平均分。

**灵感 2（痛点 = 严重度 × 不确定性）**
直觉：一个「很严重但已被反复验证」的故障**不是**痛点（我们大概知道它会怎样、也知道怎么兜）；一个「很不确定但无关痛痒」的故障也不是痛点。痛点恰恰是二者的乘积：**高后果 × 低置信**。形式化地，定义未保险痛点密度 `p(h,c) = Pain(h,c)·(1 - conf(h,c))`。它回答的是「这份不确定性此刻还欠多少期望代价」，而不是「这个故障概率多大」。这把 RAS 的「故障后验」从**分类问题**改造成了**投资组合问题**。

**灵感 3（差异化定位 → 稀缺资源的差异化，而不是功能的差异化）**
直觉：「差异化定位」在商业上问的是「我和竞品哪里不同、把资源压在哪」；迁到安全工程，就是把**验证预算 `B`** 当作稀缺资本，做差异化配置，而不是再造一层。给定每个假设的验证效率 `η_h`（每单位预算带来的置信增益），对 `p_h(1 - e^{-η_h b_h})` 做凹收益的水位分配：痛点密度越高、验证越慢的假设，分到越多预算；已经接近饱和的假设自动让位。**同一份预算下，差异化分配永远不劣于平均分配**（后文本轮定理 13）。这使「差异化定位」从口号变成一个可证的最优性命题。

**灵感 4（反棘轮 → 复杂度必须交租金）**
直觉：前 66 轮只做过「增加」，没做过「删除」。TRIAGE 第一次给出删除的判据：一个新假设只有在它的**验证价值 `VOI(h) = 期望痛点下降 - 验证成本` 大于其复杂度租金**时才被接纳，否则进入剪枝集 `Π`。这不是为了极简而极简，而是因为每多一个假设，就会摊薄其余假设的预算、并引入新的误归因通道。**「不加」本身是一种安全行为。**

**灵感 5（三灵感合流 → TRIAGE）**
TRIAGE 在 RAS 证书之上加「分诊层」，复用时序结构：
1. **PPM（Pain Profile Miner）**：按部署语境 `c` 估计每个故障假设的后果分布与置信；
2. **PDM（Pain Density Map）**：合成未保险痛点密度 `p(h,c)`，并叠加 CVaR 尾风险；
3. **WFA（Water-Filling Allocator）**：在预算 `B` 下做差异化预算分配 `b*`；
4. **CCF（Catastrophic Confidence Floor）**：对灾难性假设设置不可谈判的置信地板；
5. **TCC（Tiered Certificate Compiler）**：把单一证书编译为 T0/T1/T2 分层证书；
6. **VRR（Verification Rent Rule）**：用复杂度租金做主动剪枝，逆转棘轮；
7. **PAA（Pain-aware Attribution）**：归因时按「痛点 × 后验」排序，优先探针最疼的未知；
8. **PAC（Pain-aware Autonomy Chunk）**：越疼的故障，不可逆前缀越短。

**一句话直觉**：VISTA/RAS 在保证「每种故障都被看见」，TRIAGE 在保证「**最疼的那一种被看得最清，且不为看不见的次要故障陪葬预算**」。

|---|---|---|---|

## 1. 形式化定义（增量：定义 245–256）

- **定义 245（TRIAGE 总览）**：`TRIAGE = (PPM, PDM, WFA, CCF, TCC, VRR, PAA, PAC)`。定位：RAS 的「意图闭环」升级为「痛点分诊闭环」。不变式：痛点画像、预算分配、证书分层、剪枝判定只在语义流离线/低频完成；实时流只读取 `tier`、`b*` 配额与当前痛点归因序，零在线拟合。
- **定义 246（部署痛点泛函）**：对部署语境 `c ∈ C`、故障假设 `h ∈ ℋ_RAS`、后果 `o`：
  `Pain(h,c) = Σ_o P(o | h,c) · ℓ(o,c)`，
  其中损失矩阵非对称，`κ = ℓ(放行 | 故障) / ℓ(误降级 | 正常) ≥ 10`；并定义尾风险 `CVaR_α[Pain]`。
- **定义 247（未保险痛点密度）**：`p(h,c) = Pain(h,c) · (1 - conf(h,c))`，其中 `conf(h,c) = LCB_δ(accuracy_h)` 为校准后的置信下界（用 RAS 的联合后验做校准，而非单帧置信）。
- **定义 248（验证收益饱和律）**：预算 `b_h ≥ 0` 下 `conf_h(b) = 1 - (1 - conf_h(0))·e^{-η_h b}`，`η_h > 0` 为验证效率；对应的痛点下降为 `r_h(b) = p_h(1 - e^{-η_h b})`，关于 `b` 凹且单调递增。
- **定义 249（差异化预算分配 / 水位解）**：`b* = argmax_{b≥0, Σ_h b_h ≤ B} Σ_h r_h(b_h)`。拉格朗日条件给出内点解 `p_h η_h e^{-η_h b_h} = μ`，即 `b_h* = (1/η_h)·ln(p_h η_h / μ)`（越疼、越难验证者分得越多；已饱和者置零）。
- **定义 250（灾难性置信地板）**：对 `Pain(h,c) ≥ P_cat` 的假设，强制 `conf_h(b_h) ≥ 1 - δ_cat`，对应最小预算 `b_h^floor = (1/η_h)·ln((1 - conf_h(0)) / δ_cat)`。若 `Σ b^floor > B`，证书直接判 `INVALID`，部署必须收紧自主权，而非「按比例削减地板」。
- **定义 251（分层证书编译）**：`J_TRIAGE = (J_RAS, {Pain_h}, {p_h}, {conf_h}, {b_h*}, tier_h, prune_set, aic_t_ver)`，其中 `tier_h ∈ {T0 灾难/确认验证, T1 严重/统计验证, T2 常规/在线监控}`。分层是**差异化定位的证书化**：不同层有不同的验证义务与失效处置。
- **定义 252（复杂度租金与剪枝）**：`VOI(h) = E[ΔPain_h | 验证 h] - cost(h)`，`rent(h) = VOI(h) - γ·complexity(h)`。接纳 `h` 当且仅当 `rent(h) > 0`；否则 `Π = {h : rent(h) ≤ 0}` 进入剪枝集。这是本线第一个显式的「删除算子」。
- **定义 253（痛点感知认证视界）**：`m_TRIAGE(h) = min(m_RAS, m_T0)` 若 `h ∈ T0`，否则 `m_RAS`；认证前缀 `k*_TRIAGE = min(k*_RAS, min_h m_TRIAGE(h))`。越疼的故障，可执行更短，留出更多人类接管窗口。
- **定义 254（痛点感知归因）**：给定残差 `ρ`，归因权重 `A(h) = p(h,c)·P(H=h | ρ) / Σ_{h'} p(h',c)·P(H=h' | ρ)`。若 `argmax_h A(h)` 落在未验证集或 `Π` 中，则触发探针而非静默降级；探针优先级正比于 `A(h)`。
- **定义 255（痛点模型干扰与共因）**：干扰集 `ℰ_T = ℰ_RAS × {E_ℓ 损失误报, E_c 语境漂移, E_cc 共因操纵}`。`E_ℓ` 捕获「部署方低报某类痛以换取更高自主」；`E_cc` 捕获「同一商业压力同时压低上报痛点与抬高上报置信」。故 `ℓ` 必须来自独立审计而非被评估方自报。
- **定义 256（TRIAGE 证书有效性）**：
  ```
  Valid(J_TRIAGE) ⇔ Valid(J_RAS)
      ∧ (∀h ∈ T0: conf_h(b_h*) ≥ 1 - δ_cat)
      ∧ (Σ_h b_h* ≤ B)
      ∧ (CVaR_α[Pain] ≤ P_max)
      ∧ audit(ℓ) = pass
  ```
  且有效性对预算单调（增加 `B` 不会使已有效证书失效），对剪枝有界（剪掉 `rent ≤ 0` 的假设，期望痛点上升不超过其验证成本）。

## 2. 本轮最大风险

**一句话**：TRIAGE 的全部最优性都建立在「痛点泛函 `Pain(h,c)` 与损失矩阵 `ℓ` 可被可信标定」之上；一旦 `ℓ` 被低报、语境漂移或灾难性尾部被系统性低估，水位分配会把预算从真正的尾部故障挪走，而剪枝规则又会**主动删除**那个「当前看起来不疼」的罕见灾难假设——于是这套「最会省预算」的机制，可能恰好成为最会**省掉安全**的机制。

**次级风险与缓解**：
1. **损失标定主观**：用独立第三方审计 + 区间损失 `[ℓ_lo, ℓ_hi]` 做鲁棒优化，取 `max` 而非点估计；
2. **CVaR 样本稀薄**：尾部分位用极值理论（EVT）外推，并保留 T0 的确认性验证而非纯统计验证；
3. **剪枝不可逆**：剪枝集 `Π` 只冻结「验证预算」，不销毁假设本体，保留廉价在线监控，随时可复活；
4. **预算度量不统一**：`B` 需统一折算（样本数/算力/探针时间/人类注意力），否则水位解失去可比性；
5. **与 RAS/LADDER 叠加过重**：分诊应作为最外层的「元控制器」，只调度、不新增感知模型，避免再次触发复杂度棘轮。

## 第 67 轮产物 · 创新点清单 v1：TRIAGE（Tail-Risk-Informed Allocation of Guaranteed Effort：痛点分诊式差异化认证）

> 承接第 66 轮 IP-224~233（RAS：情绪驱动闭环）。第 66 轮解决「谁控制、控制多少」，但把安全性写成了**严重度盲的二值谓词**：只要置信达标就放行，不区分「杯子没抓稳」与「机械臂碰到人」。本轮把「加维度的安全闭环」升级为「按痛点分诊的差异化认证」：**用痛点泛函度量后果，用未保险痛点密度分配稀缺验证预算，用灾难性置信地板兜底，用复杂度租金逆转棘轮**。
>
> IP 编号：IP-234~IP-243（共 10 个），全部为 TRIAGE 的核心组件。

## 2. 形式化定义（完整版）

**定义 245（TRIAGE 总览）** TRIAGE 把 RAS 的「意图闭环」升级为「痛点分诊闭环」：
```
TRIAGE = (PPM, PDM, WFA, CCF, TCC, VRR, PAA, PAC)
```
不变式：痛点画像、预算分配、证书分层、剪枝判定只在语义流离线/低频完成；实时流只读取 `tier`、`b*` 配额与当前痛点归因序，零在线拟合、零学习写操作。

**定义 246（部署痛点泛函）** 对语境 `c ∈ C`、故障假设 `h ∈ ℋ_RAS`、后果 `o`：
```
Pain(h,c) = Σ_o P(o | h,c) · ℓ(o,c),    κ = ℓ(false_pass | fault) / ℓ(false_downgrade | normal) ≥ 10
CVaR_α[Pain] = E[Pain | Pain ≥ VaR_α[Pain]]
```
`ℓ` 是上下文相关的非对称损失，不允许被部署方自报（见定义 255）。

**定义 247（未保险痛点密度）**
```
p(h,c) = Pain(h,c) · (1 - conf(h,c))
conf(h,c) = LCB_δ(accuracy_h | RAS 联合后验)
```
`1-conf` 是「尚未被验证覆盖的比例」，因此 `p` 是「此刻还欠的期望痛点」。

**定义 248（验证收益饱和律）** 预算 `b_h ≥ 0`：
```
conf_h(b) = 1 - (1 - conf_h(0))·e^{-η_h b}
r_h(b) = p_h·(1 - e^{-η_h b})
```
`r_h` 关于 `b` 凹、单调递增；`η_h` 由历史验证曲线的斜率标定。

**定义 249（差异化预算分配）**
```
b* = argmax_{b ≥ 0, Σ_h b_h ≤ B} Σ_h r_h(b_h)
```
内点 KKT 条件：`p_h η_h e^{-η_h b_h} = μ`，故
```
b_h* = (1/η_h)·ln(p_h η_h / μ),   截断到 [0, b_h^max]
```
痛点密度高者多分；验证效率高者少分（同样的置信更便宜）。

**定义 250（灾难性置信地板）** 对 `Pain(h,c) ≥ P_cat`：
```
conf_h(b_h) ≥ 1 - δ_cat   ⇔   b_h ≥ b_h^floor = (1/η_h)·ln((1 - conf_h(0)) / δ_cat)
```
若 `Σ_h b_h^floor > B`，`J_TRIAGE` 判 `INVALID`，必须收紧自主权；**严禁按比例削减地板**。

**定义 251（分层证书编译）**
```
J_TRIAGE = (J_RAS, {Pain_h}, {p_h}, {conf_h}, {b_h*}, tier_h, prune_set, aic_t_ver)
tier_h = T0 若 Pain_h ≥ P_cat；T1 若 Pain_h ≥ P_sev；否则 T2
```
T0：确认性验证 + 最短前缀；T1：统计验证 + 探针；T2：在线监控即可。

**定义 252（复杂度租金与剪枝）**
```
VOI(h) = E[ΔPain_h | 验证 h] - cost(h)
rent(h) = VOI(h) - γ·complexity(h)
h 被接纳 ⇔ rent(h) > 0；否则 h ∈ Π = {h : rent(h) ≤ 0}
```
剪枝只冻结验证预算，不销毁假设本体，保留廉价在线监控，可随时复活。

**定义 253（痛点感知认证视界）**
```
m_TRIAGE(h) = min(m_RAS, m_T0) 若 h ∈ T0，否则 m_RAS
k*_TRIAGE = min(k*_RAS, min_h m_TRIAGE(h))
```

**定义 254（痛点感知归因）**
```
A(h) = p(h,c)·P(H=h | ρ) / Σ_{h'} p(h',c)·P(H=h' | ρ)
```
若 `argmax_h A(h)` 未验证或属于 `Π`，触发探针；探针优先级 = `A(h)`。

**定义 255（痛点模型干扰与共因）**
```
ℰ_T = ℰ_RAS × {E_ℓ 损失误报, E_c 语境漂移, E_cc 共因操纵}
```
`E_ℓ`：低报某类痛以换取更高自主；`E_cc`：同一商业压力同时压低上报痛点、抬高上报置信。故 `ℓ` 必须由独立审计给出。

**定义 256（TRIAGE 证书有效性）**
```
Valid(J_TRIAGE) ⇔ Valid(J_RAS)
    ∧ (∀h ∈ T0: conf_h(b_h*) ≥ 1 - δ_cat)
    ∧ (Σ_h b_h* ≤ B)
    ∧ (CVaR_α[Pain] ≤ P_max)
    ∧ (audit(ℓ) = pass)
```
有效性对 `B` 单调；剪枝 `rent ≤ 0` 的假设，期望痛点上升不超过其 `cost(h)`。

```python
# IP-234/235 PPM + PDM
class PainProfileMiner:
    def estimate(self, context, joint_post, logs, loss_audit):
        profile = {}
        for h in joint_post:                      # h ∈ ℋ_RAS
            cons = empirical_consequence(logs, h, context)
            pain = sum(P(o) * loss_audit.loss(o, context) for o in cons)
            c0   = lcb_accuracy(joint_post, h, delta=0.05)
            eta  = fit_saturation(logs, h)         # conf(b)=1-(1-c0)e^{-eta b}
            profile[h] = {'pain': pain, 'conf0': c0, 'eta': max(eta, 1e-6)}
        return profile


class PainDensityMap:
    def density(self, profile):
        p = {h: v['pain'] * (1 - v['conf0']) for h, v in profile.items()}
        return p, cvar(p, alpha=0.95)              # 尾风险一并输出


# IP-237 CCF：灾难性置信地板
class CatastrophicConfidenceFloor:
    def __init__(self, P_cat, delta_cat):
        self.P_cat, self.delta_cat = P_cat, delta_cat

    def min_budget(self, profile):
        floors = {}
        for h, v in profile.items():
            if v['pain'] >= self.P_cat:
                floors[h] = max(0.0, math.log((1 - v['conf0']) / self.delta_cat)
                                     / v['eta'])
        return floors


# IP-236 WFA：差异化预算分配
class WaterFillingAllocator:
    def allocate(self, p, profile, floors, B, eps=1e-6):
        b = dict(floors)                           # 先锁死灾难性地板
        if sum(b.values()) > B:
            return None                            # 预算不足 → INVALID
        rem = B - sum(b.values())
        while rem > eps:
            def marginal(h):
                return p[h] * profile[h]['eta'] * math.exp(-profile[h]['eta'] * b[h])
            h = max(p, key=marginal)
            db = min(rem, max(eps, 0.01 * rem))
            b[h] += db
            rem -= db
        return b


# IP-239 VRR：复杂度租金 / 剪枝
class VerificationRentRule:
    def __init__(self, gamma=0.1):
        self.gamma = gamma

    def rent(self, voi, cost, complexity):
        return voi - cost - self.gamma * complexity

    def prune(self, hypotheses):
        return {h for h, v in hypotheses.items()
                if self.rent(v['voi'], v['cost'], v['complexity']) <= 0}


# IP-238 TCC：分层证书编译
class TieredCertificateCompiler:
    def __init__(self, P_cat, P_sev, delta_cat):
        self.P_cat, self.P_sev, self.delta_cat = P_cat, P_sev, delta_cat

    def compile(self, J_ras, profile, b, prune_set, B):
        tiers = {}
        for h, v in profile.items():
            if v['pain'] >= self.P_cat:  tiers[h] = 'T0'
            elif v['pain'] >= self.P_sev: tiers[h] = 'T1'
            else:                         tiers[h] = 'T2'
        t0_ok = all(self._conf(profile[h], b[h]) >= 1 - self.delta_cat
                    for h in tiers if tiers[h] == 'T0')
        valid = (Valid(J_ras) and t0_ok and sum(b.values()) <= B)
        return {'J_ras': J_ras, 'tiers': tiers, 'alloc': b,
                'prune': prune_set, 'valid': valid}

    def _conf(self, v, b):
        return 1 - (1 - v['conf0']) * math.exp(-v['eta'] * b)


# IP-240 PAA：痛点感知归因
def pain_aware_attribution(joint_post, p):
    raw = {h: p[h] * joint_post.get(h, 0.0) for h in p}
    z = sum(raw.values()) or 1.0
    return {h: v / z for h, v in raw.items()}


# IP-243 总装：TRIAGE 轮
def TRIAGE_round(M, obs, context):
    # 1) 复用 RAS：得到 k_ras, λ_risk, joint_post, face_gate
    k_ras, lam, joint_post, face_gate = RAS_round(M, obs)

    # 2) PPM + PDM：痛点画像与未保险密度
    profile = M.ppm.estimate(context, joint_post, M.logs, M.loss_audit)
    p, tail = M.pdm.density(profile)

    # 3) CCF + WFA：地板与差异化分配
    floors = M.ccf.min_budget(profile)
    b = M.wfa.allocate(p, profile, floors, M.B)
    if b is None:                                  # 地板都满足不了
        return {'valid': False, 'restrict_autonomy': True, 'tail': tail}

    # 4) VRR + TCC：剪枝与分层证书
    prune_set = M.vrr.prune(M.voi_table)
    cert = M.tcc.compile(M.vista.cert, profile, b, prune_set, M.B)

    # 5) PAC：痛点感知认证前缀
    k_tri = min(k_ras, M.pac.horizon(profile))

    # 6) PAA：归因排序 + 探针
    attr = pain_aware_attribution(joint_post, p)
    h_star = max(attr, key=attr.get)
    if h_star in prune_set or profile[h_star]['conf0'] < M.tau_probe:
        M.fas.choose_probe(h_star)                 # 探最疼的未知

    # 7) 执行（前缀不变，只有分诊层决定调度与配额）
    tau_cmd = M.vista.pi_sigma.prefix_dispatch(M.vista.ach.propose(...)[:k_tri])
    tau_cmd = tau_cmd * lam
    return k_tri, b, cert, attr, tail
```

## 4. 推导

**引理 11（水位分配的 KKT 最优性与贪心收敛）** 若 `r_h` 关于 `b_h` 凹、单调递增，则问题
`max Σ_h r_h(b_h) s.t. Σ b_h ≤ B` 的 KKT 点
`p_h η_h e^{-η_h b_h} = μ`（未截断时）为全局最优；以无穷小步长、每步分配给当前边际收益最大者的贪心算法收敛到该 KKT 点。
*证明要点*：目标可分离且凹，约束为单一线性预算，Slater 条件成立；贪心每步等价于坐标上升，且凹函数的边际收益递减，故不会振荡，极限满足 KKT。∎

**引理 12（均值最优会饿死尾部）** 存在语境与预算，使最大化期望痛点下降的分配给灾难性假设 `b=0`，而地板约束强制其获得正预算。
*构造*：`h_A`：`Pain=100`，`conf_0=0.99`，`η=1`（灾难性，`P_cat=10`，`δ_cat=0.001`）；`h_B`：`Pain=2`，`conf_0=0`，`η=1`；`B=3`。则 `p_A=1`、`p_B=2`。无地板时 KKT 解为 `b_A=0`、`b_B=3`（`h_A` 已"看起来够好"）；但地板要求 `b_A ≥ ln(0.01/0.001)=2.303`，于是真实可行解必须从 `h_B` 挪走 2.303 给 `h_A`。∎
*含义*：尾风险约束不能被均值优化自动满足，`CCF` 是独立且必要的组件。

**引理 13（剪枝的痛点上界）** 对任意 `h ∈ Π`（`rent(h) ≤ 0`），剪掉它造成的期望痛点上升不超过 `cost(h) + γ·complexity(h)`。
*证明要点*：`VOI(h)=E[ΔPain_h]-cost(h) ≤ rent(h)+γ·complexity(h) ≤ γ·complexity(h)`；取期望并求和即得。该界依赖 `VOI` 估计的可信性，`E_ℓ` 会使其退化（见定理 13 与风险节）。∎

**定理 11（分层证书的端到端痛点一致性）** 在 A87–A91 与定义 256 下，若 `Valid(J_TRIAGE)=True`，则部署的最坏期望痛点满足
```
P( Pain_deploy > P_max + ε ) ≤ |T0|·δ_cat + δ_est + α_chunk
```
其中 `δ_est` 为 `Pain/conf` 的标定误差。
*证明要点*：对 `T0` 用并集界（每个假放行概率 ≤ `δ_cat`）；对 `T1/T2` 用 `b*` 的预算约束与引理 11 的收益下界；`CVaR_α ≤ P_max` 控制尾部；再叠加 RAS 的 `α_chunk + δ_fi`。∎

**定理 12（差异化定位的支配性）** 固定预算 `B`，令均匀分配 `u_h = B/|H|`，则
```
Σ_h r_h(b_h*) ≥ Σ_h r_h(u_h)
```
且当各假设的边际收益在 `u` 处不全相等时严格成立。
*证明要点*：`b*` 是可行域上的最大值点，`u` 可行；严格性来自凹函数在异质边际收益下的 Jensen 间隙。∎
*含义*：「差异化定位」不是叙事，而是同预算下的弱支配策略；痛点异质性越大，收益越大。

**定理 13（复杂度棘轮有界）** 设第 66 轮系统假设集为 `H_66`，经 VRR 剪枝后为 `H_67 = H_66 \ Π`。则
```
E[Pain(H_67)] ≤ E[Pain(H_66)] + Σ_{h∈Π} (cost(h) + γ·complexity(h))
```
即剪枝不会使期望痛点无界上升；棘轮被「租金」约束住。
*证明要点*：逐项应用引理 13；注意该界是**保守界**，当 `VOI` 被 `E_ℓ` 高估时会失效——这正是本轮最大风险。∎

## 7. 预注册预期结果（本轮未跑真实实验，以下为可证伪预期）

1. `E252` 在痛点异质性最高的三组语境中，水位分配的收益显著高于均匀分配；在痛点同质的合成语境中差异应趋近于 0（这是定理 12 的严格性条件）。
2. `E253` 若去掉 `CCF`，稀有灾难的假放行率会随预算收紧而上升；加入 `CCF` 后 T0 违规应为 0，但 `T1/T2` 的验证预算会被挤占——预期 `T2` 监控漏报轻微上升，这是可接受的显式权衡。
3. `E254` 若剪枝后痛点上升超过 `Σ(cost+γ·complexity)`，则说明 `VOI` 估计已被 `E_ℓ` 污染，应触发 `INVALID` 而非继续剪枝。
4. `E258` 若审计检出率低于 90%，则 `κ` 与 `Pain` 的秩可能已被操纵，所有分配结论不可信。

## 8. 本轮最大风险

**一句话**：TRIAGE 的全部最优性都建立在「痛点泛函 `Pain(h,c)` 与损失矩阵 `ℓ` 可被可信标定」之上；一旦 `ℓ` 被低报、语境漂移或灾难性尾部被系统性低估，水位分配会把预算从真正的尾部故障挪走，而剪枝规则又会**主动删除**那个「当前看起来不疼」的罕见灾难假设——于是这套「最会省预算」的机制，可能恰好成为最会**省掉安全**的机制。

**次级风险与缓解**：
1. **损失标定主观**：独立第三方审计 + 区间损失 `[ℓ_lo, ℓ_hi]` 做鲁棒优化，取最坏情形而非点估计；
2. **CVaR 样本稀薄**：尾部分位用极值理论外推，`T0` 保留确认性验证而非纯统计验证；
3. **剪枝不可逆**：`Π` 只冻结验证预算，不销毁假设本体，保留廉价在线监控，可复活；
4. **预算度量不统一**：`B` 需统一折算样本/算力/探针时间/人类注意力，否则水位解失去可比性；
5. **与 RAS/LADDER 叠加过重**：TRIAGE 只做最外层元控制器，只调度、不新增感知模型，避免再次触发复杂度棘轮。
