# 第 56 轮（承接第 55 轮语义-接触层 / 第 54 轮 v31；灵感循环第 2 轮；本轮灵感：「模块化设计」×「工具调用」）

> 第 55 轮把可行性下探到“语义-接触是否可信、全身耦合下是否可行”，但签发的仍是**单体技能或整条技能序列**的证书。本轮换一个组织学问题：**当系统由大量可复用模块组成、并由（VLA/LLM）规划器在运行时动态“调用”它们时，安全还能不能靠“每个模块各自有证书”来保证？** 核心矛盾：**H24**：模块化把一个大证书拆成一串小证书，但局部证书的合取**不蕴含**组合安全——模块之间隔着“接口间隙”（A 的保证并不恰好等于 B 的依赖），且全身资源是共享且被消耗的；**H25**：工具调用是**开放世界、乐观**的操作，调用者按语义描述选工具，却看不见被调模块的前置条件是否真的成立，于是“schema 匹配”被误当成“执行许可”。

## 0. 直觉与动机

**灵感 1（模块化设计 → 接口契约与信息隐藏，而非把技能切碎）**
直觉：模块化不是“函数更小”，而是**信息隐藏 + 显式接口**。一个全身模块 `M` 应暴露类型化端口：状态/位姿端口、接触端口（它将消耗哪些接触）、资源端口（力矩/质心裕度/时间预算）、权限端口（哪一层规划器可调用）与语义端口（所需标签/可供性）。模块的局部证书只相对于它的接口假设成立；离开了接口谈“这个模块是安全的”没有意义。

**灵感 2（工具调用 → 前置条件是“见证”，不是调用者的信念）**
直觉：LLM 的工具调用是 `call(name, args)`，靠 schema 与描述匹配；机器人上这等于“按名字和说明书相信它能用”。正确做法是**被调方在调用前交见证**：给出满足前置谓词的具体状态/接触/资源读数 `w`，否则返回类型化拒绝 `⊥_e`。调用成功不是“模型觉得可以”，而是“存在一个可核验的见证”。

**灵感 3（组合的 soundness = rely-guarantee 逐边放电）**
直觉：若模块 A 在共享端口上的**保证** `Post_A` 蕴含模块 B 的**依赖** `Pre_B`，且全局资源账本不超支，则组合 sound。局部证书的简单合取 `∧ Cert_i` 会把“A 说它安全”“B 说它安全”拼成“A;B 安全”，这是错的——缺的正是中间那条蕴含。接口间隙 `g(A,B)` 就是这条蕴含的违背量，必须被显式计量并设预算。

**灵感 4（模块复用 → 证书是可缓存资产，但会随版本失效）**
直觉：模块化的收益来自复用，复用就要缓存证书；但契约一升级，所有依赖它的证书都可能失效。因此需要**证书依赖图**与**变更影响分析**：模块升级触发吊销闭包，或在“新契约在旧域上后置条件不弱化”时做局部重证。否则就是供链式的“带病复用”。

**灵感 5（全身资源 → 模块不能各签各的账，必须全局结算与回滚）**
直觉：全身是资源耦合系统：接触点、摩擦锥、关节力矩、质心支撑多边形、时间都是有限且共享的。每个模块单独可行，合起来可能超支或争用同一支撑面。于是把组合写成**资源账本**：调用即预留，逐分量求和，共享接触需显式声明，失败即回滚释放。资源是“被消耗”的，不是“各模块各有一份”。

**灵感 6（失败即类型 → 结构化拒绝驱动重调用）**
直觉：工具调用要可恢复，失败就不能是布尔值。拒绝应携带 `(谓词 id, 裕度, 证据快照, 修复建议)`：让调用者能重参数化、换模块、升权限或中止。这把第 54 轮的 Explain 从“事后解释”提前成“调用前的可操作错误”，使工具调用从脆弱变可闭环。

## 1. 形式化定义（增量：定义 127–132）

**定义 127（可调用模块与契约签名）**
模块 `M=(π_M, Γ_M)`，契约签名
`Γ_M=(I_M, O_M, Pre_M, Post_M, Res_M, Auth_M, Cert_M, Fail_M)`：
- `I_M` 输入端口（目标位姿、物体/语义标签、接触类型等）；`O_M` 输出端口（终止状态、产出接触集、可观测事实）；
- `Pre_M(x,κ): X×K→[0,1]` 前置谓词及其裕度函数；`Post_M(x,x')` 后置关系；
- `Res_M∈ℝ^r_{≥0}` 资源需求（接触槽位、摩擦、力矩、质心裕度、时间）；
- `Auth_M` 调用权限；`Cert_M` 局部证书（承第 55 轮 WBV/SCC）；`Fail_M` 类型化失败集合。
称 `Γ_M` **诚实（honest）**：`∀x⊨Pre_M`，`π_M` 要么到达 `x'⊨Post_M` 且兑现 `Res_M`，要么返回 `f∈Fail_M` 且不违反 `𝒳_safe`。

**定义 128（调用裁决与见证）**
工具调用 `call(M,a)` 在 `(x,κ)` 处**可采纳**当且仅当存在见证 `w` 使 `Verify(w,Pre_M(x,a,κ))=1`；否则边端返回类型化拒绝
`⊥_e=(pred_id, m<0, evidence, repair_hint)`。
调用语义：
`call(M,a) → ⟨ok,x',O⟩ | ⟨refuse,e⟩ | ⟨fault,f⟩`，
其中 `fault` 表示安全违反，要求 `P(fault)≤ε_fault`。见证是**可信执行的前提**，不是调用者的信念。

**定义 129（接口蕴含与组合间隙）**
对调用边 `A→B`，设 `Post_A^p` 为 A 在共享端口 `p` 上的保证，`Pre_B^p` 为 B 的依赖，裕度 `m_{Pre_B}(x)≥0` 表示前置被满足的程度。组合间隙
`g(A,B)=max(0, sup_{x⊨Post_A^p} -m_{Pre_B}(x))`。
`g=0` 表示保证蕴含依赖（rely-guarantee 放电）；`g>θ_g` 则该边不可组合。它检查的是**语义/接触/资源三端口的逻辑蕴含**，不是动作向量是否相似。

**定义 130（资源账本与共享接触）**
调用路径 `P=M_1…M_n`，
`R(P)=Σ_i Res_{M_i}(a_i)+Σ_i Overhead(M_i,M_{i+1})`。
组合可行要求逐分量 `R(P)≤B_total`，且未声明共享时接触支撑集两两不交：
`supp(λ_i)∩supp(λ_j)=∅ (i≠j)`。资源是被消耗且可争用的，因此账本需支持**预留/回滚**：执行失败即释放。

**定义 131（模块化组合证书）**
`J_mod=(G_call,{Γ_i},{g_e},R(P),Cert_global,δ_mod,evidence)`，其中 `G_call` 为调用 DAG，`Cert_global=⊓_i Cert_{M_i}` 仅在 relies 逐边放电后取交，`δ_mod` 为模块版本漂移。可部署当且仅当
`∀e: g_e≤θ_g ∧ R(P)≤B_total ∧ Cert_global 成立 ∧ δ_mod≤Θ_mod`。
即 **局部证书 × 接口蕴含 × 资源结算** 三者同时闭合，缺一不可。

**定义 132（证书依赖图与失效传播）**
`G_cert=(V_cert,E_dep)`，`c_i→c_j` 表示 `c_i` 依赖模块 `M_j` 的契约。升级 `M_j→M_j'` 触发失效闭包
`Rev(M_j)={c∈V_cert | c ⇝ c_j}`。
版本漂移 `δ_ver(M_j)=d(Γ_{M_j},Γ_{M_j'})`；若 `δ_ver≤Θ_ver` 且新契约在旧域上保持后置条件（`Post'|_{Dom}⊇Post`），可**局部重证**，否则整簇吊销。部署要求 `G_cert` 无环且所有祖先证书新鲜。

## 2. 关键算法 伪代码

### IP-127 MCS（Module Contract Schema）

```python
def compile_module_contract(module, calib_set):
    Pre  = learn_precondition(module.policy, calib_set)   # 可采纳域 + 裕度函数 m_Pre
    Post = learn_postcondition(module.policy, calib_set)  # 端口级保证
    Res  = measure_resource(module, calib_set)            # contact/friction/torque/CoM/time
    Cert = local_certificate(module, calib_set)           # 承第55轮 WBV+SCC
    return Contract(id=module.id, version=module.version, ports=module.ports,
                    Pre=Pre, Post=Post, Res=Res, Auth=module.auth,
                    Cert=Cert, Fail=module.fail_taxonomy)
```

### IP-128 CWG（Call Witness Guard）

```python
def call_with_witness(M, a, x, kappa, theta_margin):
    w = build_witness(x, kappa, M.Pre, a)          # 状态/接触/资源读数
    if w is None or w.margin < theta_margin:
        return ('refuse', Refusal(pred=w.violated if w else 'no_witness',
                                  margin=w.margin if w else -inf,
                                  evidence=snapshot(x, kappa),
                                  repair=repair_hint(M, x, a)))
    u = semantic_shield(M.nominal(a), x, M.Cert.Kernel, M.Cert.C_plus, W)
    if u is None:
        return ('refuse', Refusal('shield_infeasible', 0.0, snapshot(x, kappa), 'brake'))
    return execute(M, a, u, witness=w)             # 带见证执行，见证入证书证据
```

### IP-129 RGC（Rely-Guarantee Composer）

```python
def check_composition(G_call, contracts, theta_g):
    gaps = {}
    for (A, B) in G_call.edges:
        for p in shared_ports(A, B):
            post = contracts[A].Post.port(p)
            pre  = contracts[B].Pre.port(p)
            g = max(0.0, sup_margin_violation(post, pre))   # 最坏采样 + 区间包络上界
            gaps[(A, B, p)] = g
            if g > theta_g:
                return ('reject', 'interface_gap', (A, B, p), g)
    return ('ok', gaps)
```

### IP-130 RLC（Resource Ledger Calculus）

```python
def resource_ledger(P, contracts, B_total):
    R, holds = zero_vector(len(B_total)), []
    for M, a in P:
        need = contracts[M].Res(a)
        R = R + need
        for s in need.supports:
            if overlaps(s, holds) and not need.declares_shared:
                return ('reject', 'resource_conflict', s)
        holds.append(need.supports)
    R = R + transition_overhead(P)
    if any(R[i] > B_total[i] for i in range(len(R))):
        return ('reject', 'budget_exceeded', R)
    return ('ok', Ledger(R, holds))                # 支持预留/回滚
```

### IP-131 MCC（Modular Composition Certificate）

```python
def modular_certificate(P, G_call, contracts, budgets):
    ok, gaps = check_composition(G_call, contracts, budgets.theta_g)
    if ok != 'ok':
        return ('reject', gaps)
    ok, led = resource_ledger(P, contracts, budgets.B_total)
    if ok != 'ok':
        return ('reject', led)
    cert_global = meet_all(contracts[M].Cert for M, _ in P)
    if not cert_global.holds:
        return ('reject', 'local_cert_fail')
    delta_mod = module_version_drift(P, contracts)
    if delta_mod > budgets.Theta_mod:
        return ('reject', 'version_drift', delta_mod)
    return ('ok', ModCert(G_call, contracts, gaps, led, cert_global, delta_mod))
```

### IP-132 CDR（Certificate Dependency Revocation）

```python
def revoke_on_upgrade(M_old, M_new, G_cert, theta_ver):
    dver = contract_distance(M_old.Cert, M_new.Cert)
    dom_ok = keeps_post_on_old_domain(M_old, M_new)
    if dver <= theta_ver and dom_ok:
        return ('local_revalidate', direct_dependents(M_new.id, G_cert))
    closure = transitive_closure_reverse(G_cert, M_new.id)
    return ('revoke', closure)                     # 整簇失效，禁止带病复用
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| MCS | O(\|D_cal\|·(\|X\|+\|A\|)) | O(\|ports\|+\|Fail\|) | Pre/Post 校准、资源测量完备 |
| CWG | O(\|Pre\|+QP) 每次 | O(\|w\|) | 见证 sound（无假阳性）、护盾回退 |
| RGC | O(\|E_call\|·\|ports\|·N_sup) | O(\|E_call\|) | 端口蕴含上界 sound、间隙上界紧致 |
| RLC | O(\|P\|·(r+\|supp\|)) | O(\|P\|·\|supp\|) | 资源单调、共享声明完备 |
| MCC | O(RGC+RLC+\|P\|) | O(\|V_cert\|) | 三条件联合闭合 |
| CDR | O(\|V_cert\|+\|E_dep\|) | O(\|V_cert\|) | 依赖图无环、吊销闭包完备 |

**正确性定理（Modular Tool-Call Soundness）**
假设第 55 轮 (A29)–(A32) 成立；**(A33)** 每个模块契约在其域上诚实；**(A34)** 每条调用边 `g_e≤θ_g`；**(A35)** 资源账本保守且共享接触声明完备；**(A36)** 见证校验无假阳性（校准误差 ≤ ε_w）；**(A37)** 证书依赖图无环且吊销闭包完备。
则对长度 `n` 的调用路径 `P`：
```
P_safe(P) ≥ 1 - Σ_i P(local fault_i) - P(∃e: g_e > θ_g)
              - P(R(P) > B_total) - n·ε_w - P(missed revocation)
```
关键：**局部证书只是原料；接口蕴含负责“接线正确”，资源账本负责“总量不超支”，见证负责“调用前真的接得上”。**

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| `Pre` 学得过宽，假见证放行 | 高 | 保守校准 + 多源一致见证 + 运行时裕度 |
| 接口间隙上界欠采样，组合失配 | 高 | 最坏情形采样 + 区间包络 + 未知即拒绝 |
| 资源不可加（摩擦/力矩非线性） | 高 | 分量账本 + 非线性耦合预留 + 在线结算 |
| 工具描述与真实契约漂移，选错工具 | 高 | 契约即 schema + 描述由契约生成 + 调用前见证 |
| 吊销风暴，可用性下降 | 中 | 细粒度契约版本 + 局部重证 + 证明缓存 |
| 模块过多，组合爆炸 | 中 | 类型化端口匹配剪枝 + 层次化模块 |

## 6. 本轮最大风险

**一句话**：模块化设计 × 工具调用把单体证书拆成可复用、可调用的契约单元，但其 soundness **四重依赖前置条件见证无假阳性、接口蕴含上界紧致、资源账本对非线性耦合保守、以及证书吊销闭包完备**；一旦任一环节把“接口看起来匹配”当成“物理上可组合”，调用图会串起一串各自合格却整体越界或错位的模块，让全身控制器在合法契约的名义下执行一个非法计划——因此必须以 **见证守卫 + 区间上界 + 资源结算 + 吊销闭包** 四道闸门，宁可拒绝调用，也绝不把 schema 匹配当成执行许可。

# 第 56 轮产物 · 创新点清单 v32：ModuCall-GroundEdge（MCS×CWG×RGC×RLC×MCC×CDR）

> 承接第 54 轮产物 v31（ACS×SCOM×CEC×AEC×JTC）与第 55 轮想法区「语义-接触生存核」（IP-121~126：SCG/WBV/SSF/SCC/SRS/CEB）。本轮新增 **可调用模块契约层（Modular Tool-Call Layer）**：把“可复用模块”写成带类型化端口的契约，把“工具调用”写成带前置见证的裁决，并用依赖-保证、资源账本与证书吊销把组合安全闭合。
>
> IP 编号：**IP-127~IP-132（本轮新增 6 个）**；继承并升级 IP-115~120（动作-协同层）与 IP-121~126（语义-接触层）。

| `R(P)=Σ Res_{M_i}+Σ Overhead` | 资源账本 |
| `J_mod=(G_call,{Γ_i},{g_e},R(P),Cert_global,δ_mod)` | 模块化组合证书 |

### IP-128 CWG（Call Witness Guard）

```python
def call_with_witness(M, a, x, kappa, theta_margin):
    w = build_witness(x, kappa, M.Pre, a)
    if w is None or w.margin < theta_margin:
        return ('refuse', Refusal(pred=w.violated if w else 'no_witness',
                                  margin=w.margin if w else -inf,
                                  evidence=snapshot(x, kappa),
                                  repair=repair_hint(M, x, a)))
    u = semantic_shield(M.nominal(a), x, M.Cert.Kernel, M.Cert.C_plus, W)
    if u is None:
        return ('refuse', Refusal('shield_infeasible', 0.0, snapshot(x, kappa), 'brake'))
    return execute(M, a, u, witness=w)
```

### IP-129 RGC（Rely-Guarantee Composer）

```python
def check_composition(G_call, contracts, theta_g):
    gaps = {}
    for (A, B) in G_call.edges:
        for p in shared_ports(A, B):
            post = contracts[A].Post.port(p)
            pre  = contracts[B].Pre.port(p)
            g = max(0.0, sup_margin_violation(post, pre))   # 最坏采样 + 区间包络上界
            gaps[(A, B, p)] = g
            if g > theta_g:
                return ('reject', 'interface_gap', (A, B, p), g)
    return ('ok', gaps)
```

### IP-130 RLC（Resource Ledger Calculus）

```python
def resource_ledger(P, contracts, B_total):
    R, holds = zero_vector(len(B_total)), []
    for M, a in P:
        need = contracts[M].Res(a)
        R = R + need
        for s in need.supports:
            if overlaps(s, holds) and not need.declares_shared:
                return ('reject', 'resource_conflict', s)
        holds.append(need.supports)
    R = R + transition_overhead(P)
    if any(R[i] > B_total[i] for i in range(len(R))):
        return ('reject', 'budget_exceeded', R)
    return ('ok', Ledger(R, holds))                # 预留/回滚：失败即释放

def execute_with_rollback(P, contracts, ledger):
    reserved = ledger
    for M, a in P:
        ok, res = call_with_witness(contracts[M], a, state(), kappa(), theta_margin)
        if ok == 'refuse':
            return ('rollback', reserved.release_all(), res)   # 释放本路径全部预留
        if ok == 'fault':
            return ('safe_brake', res)
    return ('ok', reserved.commit())
```

### IP-131 MCC（Modular Composition Certificate）

```python
def modular_certificate(P, G_call, contracts, budgets):
    ok, gaps = check_composition(G_call, contracts, budgets.theta_g)
    if ok != 'ok':
        return ('reject', gaps)
    ok, led = resource_ledger(P, contracts, budgets.B_total)
    if ok != 'ok':
        return ('reject', led)
    cert_global = meet_all(contracts[M].Cert for M, _ in P)
    if not cert_global.holds:
        return ('reject', 'local_cert_fail')
    delta_mod = module_version_drift(P, contracts)
    if delta_mod > budgets.Theta_mod:
        return ('reject', 'version_drift', delta_mod)
    return ('ok', ModCert(G_call, contracts, gaps, led, cert_global, delta_mod))
```

```python
def revoke_on_upgrade(M_old, M_new, G_cert, theta_ver):

    dom_ok = keeps_post_on_old_domain(M_old, M_new)
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| MCS | O(\|D_cal\|·(\|X\|+\|A\|)) | O(\|ports\|+\|Fail\|) | Pre/Post 校准、资源测量完备 |
| CWG | O(\|Pre\|+QP) 每次 | O(\|w\|) | 见证 sound（无假阳性）、护盾回退 |
| RGC | O(\|E_call\|·\|ports\|·N_sup) | O(\|E_call\|) | 端口蕴含上界 sound、间隙紧致 |
| RLC | O(\|P\|·(r+\|supp\|)) | O(\|P\|·\|supp\|) | 资源单调、共享声明完备、可回滚 |
| MCC | O(RGC+RLC+\|P\|) | O(\|V_cert\|) | 三条件联合闭合 |
| CDR | O(\|V_cert\|+\|E_dep\|) | O(\|V_cert\|) | 依赖图无环、吊销闭包完备 |

**正确性定理（Modular Tool-Call Soundness）**
假设第 55 轮 (A29)–(A32) 成立；**(A33)** 每个模块契约在其域上诚实；**(A34)** 每条调用边 `g_e≤θ_g`；**(A35)** 资源账本保守且共享接触声明完备；**(A36)** 见证校验无假阳性（校准误差 ≤ ε_w）；**(A37)** 证书依赖图无环且吊销闭包完备。
则对长度 `n` 的调用路径 `P`：
```
P_safe(P) ≥ 1 - Σ_i P(local fault_i) - P(∃e: g_e > θ_g)
              - P(R(P) > B_total) - n·ε_w - P(missed revocation)
```
关键：**局部证书只是原料；接口蕴含负责“接线正确”，资源账本负责“总量不超支”，见证负责“调用前真的接得上”。**

## 5. 本轮最大风险

**一句话**：模块化设计 × 工具调用把单体证书拆成可复用、可调用的契约单元，但其 soundness **四重依赖前置条件见证无假阳性、接口蕴含上界紧致、资源账本对非线性耦合保守、以及证书吊销闭包完备**；一旦任一环节把“接口看起来匹配”当成“物理上可组合”，调用图会串起一串各自合格却整体越界或错位的模块，让全身控制器在合法契约的名义下执行一个非法计划——因此必须以 **见证守卫 + 区间上界 + 资源结算 + 吊销闭包** 四道闸门，宁可拒绝调用，也绝不把 schema 匹配当成执行许可。
