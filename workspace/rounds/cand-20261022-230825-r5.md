# 想法区 · 第 5 轮：把「时间」从变量表里删掉——序空间、证书探针，与一条不成立的支配

**灵感词**：simulated annealing / 凸包 / sat solver
**起点**：v2.2「X-DUB/PACE-ΠA-CP*」。38 例 38 节点 / 2 表 / 0.113 s，deep 8 例 8 / 6，held-out 50 例 50 / 44 表 / 3.51 s，easy 60 例 781，planted 21 例 21。它的收官风险仍然是一句话：

> CPS 用「枚举一条链的所有 placement + 精确 residual 回溯」换来了 5 个残例的根闭，但它的完备性只覆盖 `S≤4`、`n≤16`、全资格且 residual 未撞 cap 的紧状态；一旦 residual 变大或资格异构，它只能退回 unknown，最坏情况仍是 `d!`。

本轮不推倒 v2.2。我想把这句话拆成两半：一半是**覆盖门**（参数），一半是**证书的形状**（坐标系）。第 4 轮我试过动后一半——把 CPS 的叶子表升级成 placement 树上的 BFS 前缀割。数据很冷：5 个残例的 106 个 placement **全部**通过窗口传播、全部初始容量非负；idx 32 的 21 个 placement 的 residual 全是 NO，却找不到一个便宜的局部矛盾。也就是说，**叶子之上的每一个便宜测试都是通过的**。割本身没错，错在坐标系：在 CPS 里「时间」是决策变量，而便宜测试只能看见时间的一部分，看不见「顺序」。

## 一、SAT 的那句话：只 branch 在能决定其余变量的原子上

CPS 有两层「时间原子」：先枚举链上 L 个任务的起点（`C(S+L,L)` 个 placement），再对每个 placement 枚举剩余任务的起点。两层都在决定「几点开始」。

SGS（serial schedule generation scheme）把这件事反过来：**起点不是变量**。选一个「下一个排谁」的优先序 π，每个任务放在「最早可行」的位置；时间由 π 唯一决定。搜索空间从「整数起点向量」变成「优先序」，分支因子从 `h` 降到 ready 集大小。

一句话：**branch on order, propagate time.** 这正是 SAT 的教训——branch 在决定其余变量的原子上，把被决定的变量交给传播。

关键定理不是我的，是 scheduling 里的 active schedule theorem：全资格下，若存在可行排程，则存在一个 active 排程；每个 active 排程都被某个序的 SGS 复现。所以对序的穷举是**精确**的。这一点比 CPS 还强一截：CPS 的 `YES` 在异资格下只是 unknown，OS 的 `YES` 是一张可独立验证的排程（全资格下）。

## 二、凸包：两台引擎的成本曲线，和它们的下包络

把 CPS 和 OS 看成两台证书引擎：

```text
CPS 成本 ≈ placement 数 C(S+L,L) × residual 回溯
OS  成本 ≈ active 排程数（序空间的一个子集）
```

两者都指数，但指数的位置不同：CPS 的指数在「链松弛 S」上，OS 的指数在「序」上；链的优先约束会把序空间切小，所以长链对 OS 是好事、对 CPS 是中性。**没有谁支配谁**——这不是修辞，是实测：45 个合成紧状态（`S∈[0,4]`）上 CPS 只要 1–54 个 residual 节点，OS 要 177–10,001 个，**0/45 是 OS 赢**；反过来 5 个 held-out 残例上 CPS 要 16,810–37,074，OS 只要 788–2,136。两边的成本差都是 10–1000 倍，方向相反。

所以「新算法」不该是「用 OS 替换 CPS」，而该是**两台引擎成本曲线的下包络**。工程上就是 portfolio，但选谁不能靠结构启发式：我试过 `L/n`（链钉住的任务比例），合成集上 0.091–0.385，5 个残例 0.31–0.40，完全重叠，分类器不成立。

能成立的是一个**证书探针**：先让 CPS 在 300 个 residual 节点内跑。跑完，说明 CPS 是便宜的那一侧；跑不完，换 OS。为什么可行？因为 CPS 的成本是双峰的：45 个合成紧状态 1–54 节点，5 个残例 16,810–37,074，中间有 300× 的空隙，300 正好落在空隙里。探针不是猜，是**用一次真实证书尝试去问引擎自己**。

## 三、SA：为什么这一轮不给它一层（一条定理，不是懒惰）

一个反直觉但很干净的定理：**没有学习的穷举 SGS，其展开状态集与分支顺序无关**。状态是 `(mask, cap, rel)`，它的后继集是确定的；memo 让每个状态恰好展开一次。所以 NO 侧的节点数与顺序无关，随机重启/退火**不可能**减少 NO 的搜索量——它只能改变 YES 侧「第几个叶子找到可行排程」。

实测逐字证实：5 个残例在 LPT/EDD/SPT 三种确定性序 + 8 个随机种子下，节点数完全相同（788 / 1327 / 959 / 1592 / 2136）。YES 侧（`h=OPT`）才有 2.4× 的波动（50 例总节点 5,761–14,077，EDD 6,216、LPT 7,021、SPT 13,211）。

所以 SA 不是被忽略，是被一条定理挡在证书侧之外。它剩下的位置是 YES 侧的顺序搜索；但 YES 侧本来就只要 20–334 个节点，SA 的 10^3 次评估更贵。**这一轮把 SA 记成负结果**：不是「没试」，是「试了，并且证明了为什么不该再试」。

## 四、形式化的一句话版本（完整定义与证明见产物区）

- **SGS**：给定优先序 π，逐个把 π(k) 放在最早的 `t ≥ max(r_i, 已排前驱完成)` 且 `cap[t..t+p_i) ≥ 1` 的位置；若 `t > d_i − p_i`，该序失败。
- **active**：没有任务能在不推迟别的任务、不违反优先/释放的前提下左移。
- **OS**：对序做 DFS，状态 `(mask, cap, rel)`，精确 memo；全资格下 `NO ⇔ 不可行`，`YES` 带排程。
- **序树证书**：内部节点是「已定序前缀 + 状态」，叶子是 dead；大小 = 展开状态数（5 个残例共 6,802），检查器重放 SGS。
- **HY**：`CPS(300 节点)` → 若 UNKNOWN 则 `OS(10k 节点)`；任一引擎给出 NO 才是 NO。

## 五、本轮要交付什么

- **v2.3 = v2.2 的 tier 0.15 从 CPS 换成 HY**（探针 300 → OS 10k）。5 个残例：CPS 110,971 节点 / 2.01 s → OS 6,802 / 0.0717 s（16.3× / 28×）；HY 8,307 / 0.0825 s。
- **端到端 held-out 50**：50 节点 / 44 表 / 3.480 s → **1.552 s**（2.24×），50/50 判决逐例不变；38 例 38 / 2 表不变（门不触发，`cps_calls=0` 已复核）。
- **正确性**：400 组随机小实例 vs 暴力 0 不一致（184 可行）；50+12+8 张 `h=OPT` 的 YES 排程独立验证；45 个合成紧状态 OS/CPS 判决一致；4 个异资格 NO 用精确引擎复核。
- **负结果**：合成紧状态 OS 输 1000×（0/45 胜）；支配前沿省 4.5% 节点但多 67% 时间；异资格 `YES` 6/8 不可验证、并有 1 个假 YES；并行在根上宽度为 1。
- **边界**：全资格、根/浅层、`n≤16`、`S≤4`；异资格只保证 NO；没有短证书；没有 Coq/Lean。

## 六、一句话最大风险

**这一轮的 16× 不是来自一个更聪明的算法，而是来自一次「坐标系换对了」的测量：active schedule 定理只在全资格、窗口精确、整数时间下成立，而 OS 在合成短链紧状态上又会输给 CPS 1000×——所以真正的算法其实是那个 300 节点的探针，探针一旦选错（CPS 成本不再双峰），全部收益立刻反转。**

## 2. 形式定义

### 2.1 状态、窗口、容量

沿用 v2.2 的定义。给定 `σ=(R,A,est)` 与公共期限 `h`：

```text
r_i = est_i ,        d_i = h − q_i(R) ,        c_σ(t) = |{k : A_k ≤ t}| .
```

全资格时，`(r,d,c_σ,≺)` 精确刻画了剩余问题：任意满足 `r_i≤t_i`、`t_i+p_i≤d_i`、优先序、且任意时刻活跃数 `≤ c_σ(t)` 的整数起点向量，都能用区间图贪心染色落到具体机器上（v2.2 引理 2）。本轮不重复证明，直接引用。

### 2.2 序与 SGS

**定义 1（优先序）**。`π` 是 `R` 的一个排列，且对任意 `u≺v`，`u` 在 `v` 之前。记 `π_{<k}=(π_1,…,π_{k-1})`。

**定义 2（SGS 放置）**。给定 `σ` 和 `π`，递归定义：

```text
t_{π_1} = min { t ≥ r_{π_1} : cap[t..t+p_{π_1}) ≥ 1 } ,
t_{π_k} = min { t ≥ max(r_{π_k}, max_{u≺π_k, u 已排} (t_u+p_u)) :
                cap[t..t+p_{π_k}) ≥ 1 } ,
```

其中 `cap` 初始为 `c_σ`，每放一个任务就在 `[t,t+p)` 上减 1。若某步 `t > d_{π_k}−p_{π_k}`，或不存在这样的 `t`，则 `SGS(σ,π)=⊥`（该序失败）。否则输出 `t=(t_i)`。

**定义 3（active schedule）**。可行排程 `t` 是 active 的，若不存在任务 `i` 和 `t'_i<t_i`，使得把 `i` 左移到 `t'_i`、其余不动后仍然可行（即不违反 `r_i`、优先序、容量）。等价地：没有任何任务能在不推迟别的任务、不违反释放/优先的前提下左移。

### 2.3 序树与证书

**定义 4（序树）**。`T_OS(σ)` 是一棵树：

- 根是 `(∅, (R, c_σ, r))`；
- 节点 `(π_{<k}, state)` 的子节点是对每个「在 `π_{<k}` 之后可放」的任务 `i`（`pred(i)⊆π_{<k}` 且 `∃t` 合法）尝试 `SGS` 一步得到的 `(π_{<k+1}, state')`；
- 叶子是 `mask=∅`（YES）或「没有可放任务/全部超期」（dead）。

序树的一个 **NO 证书**是：所有叶子都是 dead，且每个内部节点的子节点集合恰好等于该状态的全部可放选择。

**定义 5（NO 上集）**。固定 `mask`，状态 `(cap,rel)` 上的偏序：

```text
(cap,rel) ⪯ (cap',rel')   ⇔   cap ≥ cap' 逐点 且 rel ≤ rel' 逐点 .
```

`⪯` 读作「前者比后者更宽松」。`(cap,rel)` 可行 ⇒ 任何 `(cap',rel') ⪰ (cap,rel)` 也可行；所以 NO 区域是上集（up-set）。

### 2.4 OS 的三值语义

```text
OS(σ) = NO        若 T_OS(σ) 被完整展开且所有叶子 dead（未撞 N_OS）；
        YES       若到达 mask=∅，带回溯出的排程 t（全资格时可直接验证）；
        UNKNOWN   若撞 N_OS，或非全资格。
```

### 2.5 探针组合 HY

```text
HY(σ) = CPS(σ; 全局 residual 预算 κ)
        若返回 NO/YES：直接采用；
        若返回 UNKNOWN：OS(σ; N_OS)。
```

### 2.6 触发门

沿用 v2.2 的紧状态门（覆盖门，不是可靠性门）：

```text
hy_gate(σ) = ( |R| ≤ 16 ) ∧ ( S(σ) ≤ 4 ) ∧ ( depth ≤ 0 ) ∧ 全资格 .
```

门关掉只少剪，不会多剪。`probe=300`、`os_ncap=10000` 是两个预算，不是正确性参数。

## 3. 算法

### 3.1 OS-SGS 主循环

```text
OS(σ; N_OS):
    r ← |R|; cap ← c_σ; rel ← r_σ; mask ← R
    if mask=∅: return YES([])
    if nodes > N_OS: return UNKNOWN
    key ← (mask, cap, rel|mask)
    if key ∈ memo: return NO
    Ready ← { i∈mask : pred(i)∩mask=∅ }
    cand ← [(i, EARLIEST(cap, rel_i, p_i, d_i)) for i in Ready]
    cand ← [(i,t) for (i,t) in cand if t ≠ ⊥]
    if cand=∅:
        memo.add(key); return NO
    for (i,t) in ORDER(cand):                 # 顺序不影响 NO 的节点数（定理 2）
        cap' ← cap − 1_{[t,t+p_i)}
        rel' ← rel; for j∈succ(i)∩mask: rel'_j ← max(rel'_j, t+p_i)
        sched[i] ← t
        if OS(mask\{i}, cap', rel') = YES: return YES(sched)
        del sched[i]
    memo.add(key); return NO
```

`EARLIEST` 从 `rel_i` 开始逐格检查 `p_i` 个连续容量，复杂度 `O(h+p_i)`。`ORDER` 在实现里是 LPT（`-p_i`，再 `d_i`），但**任何顺序都得到同一棵 NO 树**（定理 2）。

### 3.2 CPS 探针

```text
CPS_PROBE(σ; κ):
    chain ← CRITICAL_PATH(σ);  spent ← 0
    for s in PLACEMENTS(chain):
        left ← κ − spent
        if left ≤ 0: return UNKNOWN
        rr ← RESIDUAL(σ\chain, WINDOWS(s), CAPACITY(s), nodecap=left)
        spent += nodes(rr)
        if rr = YES: return YES
        if rr = UNKNOWN: return UNKNOWN
    return NO
```

与 v2.2 的 `CPS` 逐字相同，唯一区别是 `nodecap` 是**全局**预算而不是每个 placement 各自 300k：探针要能在 300 个节点内果断地说「CPS 这一侧不便宜」。

### 3.3 HY

```text
HY(σ):
    if ¬hy_gate(σ): return UNKNOWN
    v ← CPS_PROBE(σ; κ=300)
    if v ≠ UNKNOWN: return v
    return OS(σ; N_OS=10000)
```

```text
PACE-ΠA-OS(σ,h):
  1  if R=∅: return YES([])
  2  if DEAD(σ): return NO
  3  σ←NORM(σ); A*←CANON(A); estt←est|R

  5  window 层: energy / clique / subset / HPACK          # v2.0
  6  MINT / PACK-SET / SOP                                # v2.0
  7  if ¬PACK(σ,h): F_pack.insert; return NO(PACK)        # v2.0
  8  q ← tails(R)                                         # v2.0
  9  if MAP-gate(σ): ok ← MAP(σ); if ¬ok: return NO(MAP)  # v2.1
 10  ready ← READY(R)
 11  drop ← DHD(ready) ∪ DCD(ready)                       # v2.1
 12  if hy_gate(σ) and |ready\drop| > 0:
         v ← HY(σ)                                        # v2.3，替换 v2.2 的 CPS
         if v=NO: return NO(HY)
 13  for i in K=ready\drop:
         for k in machines(i):
             t ← max(A_k,est_i)
             if t+p_i+q_i(R\{i}) > h: continue
             r ← PACE-ΠA-OS(child(i,k,t),h)
             if r=YES: return YES([(i,k,t)]+r)
 14  F_sub.insert(estt,A*); return NO(RESOLVE)
```

与 v2.2 的差异只有第 12 步。`HY` 在 DHD/DCD 之后、分支之前调用，只做有证书的剪枝。

### 3.5 证书格式与检查

**OS-NO 证书**：

```text
kind    = 'OS'
payload = (R, A, est, q, h, [(π_prefix, (mask, cap, rel), verdict), ...])
claim   = 每个叶子 dead；每个内部节点的子节点 = 该状态的全部可放任务
```

检查器独立重放：

```text
CHECK_OS(inst, σ, tree):
    按 π_prefix 重放 SGS 的每一步（不信任 tree 里的 cap/rel，自己重算）
    对每个内部节点：验证子节点集合 = { i∈mask : pred(i)∩mask=∅, EARLIEST≠⊥ }
    对每个叶子：验证 mask=∅ 或 cand=∅
    accept iff 树覆盖根且所有叶子 dead
```

这是**重放证书**，不是短证书：检查代价与生成同阶。好处是检查器不需要信任搜索树、不需要浮点/LP，且比 CPS 的证书小得多（见 §5.2）。

**OS-YES 证书**：`π` + 起点向量 `t`。检查器验证：每个任务一次、优先序、`r≤t`、`t+p≤d`、任意时刻活跃数 `≤ c_σ(t)`；全资格下再用区间图贪心染到机器上。大小 `O(n)`。

**PAR-OS**（未实现）：序树在深度 1 的宽度是 1（唯一源任务），深度 3 才到 6–23；根切分没有并行度。见 §5.10。

### 3.6 复杂度

设 `r=|R|`，`h` 为期限，`E` 为展开状态数。

```text
OS 单状态:      O(h + r log r) 做 EARLIEST 与排序
OS 总计:        O(E · (h + r log r))，E ≤ 可行 active 排程数 ≤ r!
memo:           (mask, cap, rel) 精确键；空间 O(E·(h+r))
CPS 探针:       ≤ κ 个 residual 节点 + O(C(S+L,L)·(n+h)) 的枚举
HY:             κ + (E·(h+r log r))（探针失败时）
主搜索:         不变，N(σ)=1+Σ N(σ_i)
```

`OS` 没有打破 NP-hard：`m=1` 时它就是 `1||Lmax` 的序枚举；`m` 台、无优先时它是 `P||Cmax` 的 active 排程枚举。它把指数从「起点向量」搬到「序」，没有消除指数。

## 4. 定理与证明

### 4.1 引理 1（active 存在性）

**引理 1**。若 `σ` 存在可行排程，则存在一个 active 的可行排程。

**证明**。取所有可行排程中 `Σ_i C_i` 最小的一个 `t`。若 `t` 不是 active，则存在任务 `i` 与 `t'_i<t_i`，把 `i` 左移到 `t'_i` 后仍可行；新排程的 `ΣC` 严格更小，矛盾。整数排程有限且 `ΣC` 有下界，所以最小值存在。∎

### 4.2 引理 2（SGS 复现每个 active 排程）

**引理 2**。设 `t` 是 active 可行排程，`π` 是按 `t_i` 升序（同起点按优先序、再任意）排列的序。则 `SGS(σ,π)` 的起点向量恰为 `t`。

**证明**。对 `k` 归纳，假设前 `k−1` 个任务都放在 `t` 的位置。令 `j=π_k`。

- 先证 `SGS` 能在 `t_j` 放下 `j`：`SGS` 已放的任务都是 `t` 中起点早于 `t_j` 的任务（同起点中排在 `j` 前的也已放）；它们在 `t_j` 时刻的占用不超过 `t` 在 `t_j` 时刻的占用。`t` 可行，`j` 在 `t_j` 活跃，所以 `t` 在 `t_j` 的活跃数 ≤ `c(t_j)`；`SGS` 的已放集合是它的子集，故 `[t_j,t_j+p_j)` 仍有容量。又 `t_j ≥ max(r_j, 前驱完成)`，所以 `EARLIEST ≤ t_j`。
- 再证 `EARLIEST` 不会 `> t_j`：由上一步，`t_j` 是一个合法候选。
- 最后证 `EARLIEST` 不会 `< t_j`：若 `SGS` 把 `j` 放在 `t'_j<t_j`，则把 `t` 中的 `j` 左移到 `t'_j`：`SGS` 在该区间看到容量为空，而未放的任务在 `t` 中起点 `≥t_j>t'_j`，不占 `[t'_j,t'_j+p_j)`；已放任务与 `t` 相同。于是左移后仍可行，违反 `t` 的 active 性。矛盾。∎

### 4.3 定理 1（OS 的完备性与可靠性）

**定理 1**。全资格、窗口 `(r,d)` 精确、memo 精确且未撞 `N_OS` 时：

```text
OS(σ)=NO  ⇔  σ 不可行 ;        OS(σ)=YES ⇒ σ 可行（且带回排程）.
```

**证明**。

- `YES ⇒ 可行`：SGS 的构造保证优先序、`r≤t`、`t+p≤d`、任意时刻活跃数 ≤ `c_σ`。全资格下由 v2.2 引理 2（区间图贪心染色）把区间分配到机器，得到完整排程。∎
- `NO ⇒ 不可行`：若 `σ` 可行，引理 1 给 active 可行排程 `t`，引理 2 给一个序 `π` 使 `SGS(σ,π)=t`。OS 枚举所有优先序（每个内部节点枚举全部可放任务），故会到达 `mask=∅`，与所有叶子 dead 矛盾。∎
- `可行 ⇒ YES`：同上，OS 会找到那个 `π`；memo 只删除已经证明为 NO 的状态，不会删掉可行路径（memo 键含 `mask,cap,rel`，是后续可行性的充分统计量）。∎

**注（deadline 剪枝的合法性）**：`EARLIEST` 返回 `⊥` 时，该任务在**任何**更晚起点都只会更超期，所以这个分支确实不可能延拓；这不是近似。

### 4.4 定理 2（序不变性：SA 在 NO 侧无效）

**定理 2**。固定 `σ`，OS 使用精确 memo 且不撞 cap。则对任意两个分支顺序 `ORDER`、`ORDER'`，展开的状态集合相同，节点数相同。

**证明**。定义状态转移图 `G`：节点是 `(mask,cap,rel)`，从 `(mask,cap,rel)` 出发的后继是「对每个 `i∈Ready` 且 `EARLIEST≠⊥`，放 `i` 得到的状态」；这个集合只由状态本身决定，与访问顺序无关。DFS + memo 对每个可达状态恰好展开一次（`mask` 严格减小，无环；memo 在状态**完全展开后**才标记为 NO，所以不会把「正在展开」误判为 NO）。因此展开集 = 从根可达的状态集，节点数 = `|可达集|`，与顺序无关。∎

**推论 1**。任何随机化/退火/重启策略，只要仍是「穷举 + 精确 memo」，在 NO 实例上的节点数不变；随机性只能改变**第几个叶子**先到达 YES，即只影响 YES 侧的 time-to-solution。

**注**：这解释了 v2.2 的负结果——随机化 **residual 的变量/值顺序**之所以坏，是因为它改变了 minopts 选中的**变量**（树的结构），而不只是顺序；在 OS 里分支被限制在 Ready 集，顺序才真正只是顺序。两者不矛盾，正好互补。

### 4.5 定理 3（支配/上集）

**定理 3**。固定 `mask`。若 `(cap,rel)` 为 NO，则任何 `(cap',rel') ⪰ (cap,rel)`（`cap'≤cap`、`rel'≥rel`）也为 NO。因此「只保留 NO 状态的极小元（前沿）」是可靠且完备的剪枝。

**证明**。若 `(cap',rel')` 可行，取它的一个排程 `t`；同一 `t` 对 `(cap,rel)` 也可行（容量更大、释放更早），矛盾。完备性：被剪掉的状态都被某个已证 NO 的状态支配，由可靠性它确实 NO。∎

**实测**：前沿把 5 个残例的 6,802 节点降到 6,496（−4.5%），但时间从 0.046 s 升到 0.077 s（+67%）。原因是状态格太稀疏，前沿比较的常数大于它省下的搜索。**默认关闭**。

### 4.6 定理 4（HY 的可靠性）

**定理 4**。`HY(σ)=NO` ⇒ `σ` 不可行。

**证明**。`HY=NO` 只有两种来源：(a) `CPS_PROBE` 完整枚举了链的所有 placement 且每个 residual 都 NO——由 v2.2 的投影引理，任一可行排程都会投影到某个 placement 的可行 residual，矛盾；(b) `CPS_PROBE=UNKNOWN` 后 `OS=NO`——由定理 1。探针返回 UNKNOWN 本身不产生 NO。∎

**系**。`HY=YES` 在全资格下是可行的（CPS 的 YES 由 v2.2 定理 2，OS 的 YES 由定理 1）；异资格下 `HY` 直接返回 UNKNOWN（门），不会假 YES。

### 4.7 定理 5（集成保持完备性）

**定理 5**。PACE-ΠA-OS 只可能比 v2.2 多剪「已证明 NO」的状态；未被剪的状态仍按 v2.1/v2.2 的 DHD/DCD 分支。因此 `YES ⇒ 可行`，且存在可行排程时不会返回 NO。

**证明**。第 12 步的剪枝由定理 4 给出 NO 证书；其余步骤逐字是 v2.2。对搜索树归纳：被剪子树确实无解；未剪分支覆盖 v2.2 的全部分支。∎

### 4.8 命题 1（CPS 与 OS 互不支配）

**命题 1（实测，非定理）**。在 45 个合成紧状态（`n=11–16`、`m=3–4`、`S∈[0,4]`、全资格）上：

```text
CPS 总 residual 节点 1–54；OS 节点 177–10,001（29/45 撞 10k cap）；OS 胜 0/45。
```

在 5 个 held-out 残例上：

```text
CPS 16,810–37,074；OS 788–2,136；OS 胜 5/5。
```

所以不存在「OS 支配 CPS」的命题；本轮只主张「在 held-out 这一族上 OS 更便宜」，并用探针在运行时判定。

### 4.9 命题 2（异资格反例：OS 的 YES 会失真）

**命题 2**。异资格下 `OS=YES` 不蕴含可行。

**反例**（v2.2 §4.2 的同一构造）：`m=2`，`A=(6,0)`，`h=10`，链 `i≺j`，`p_i=p_j=4`，`i` 只 eligible 机器 0，`j` 只 eligible 机器 1。容量模型说 `[0,8)` 上只占 1 台，`j` 从 4 开始可行；实际 `i` 最早 6 点开始、10 点结束，`j` 必须 10 点后开始，超期。OS 的 `EARLIEST` 只看聚合容量，会给出 YES。**实测**：`large_het` 8 例在 `h=OPT` 上 OS 返回 8 个 YES，精确机器分配（回溯）只有 2 个能落地（6/8 失真）；idx 1 在 `h=OPT−1` 返回 YES，而精确引擎是 NO（假 YES）。所以门里必须有全资格。

### 4.10 命题 3（NP-hard 不变）

**命题 3**。OS 没有打破 NP-hard：`m=1`、无优先时，序空间就是 `n!`，判定等价于 `1||Lmax`；`m` 台、无优先时等价于 `P||Cmax` 的 active 排程枚举。CPS 的 residual 同样含 `P||Cmax`。两者都指数，只是指数的位置不同。

### 5.7 支配前沿：一个诚实的负结果

| 变体 | 5 例总节点 | 时间 |

前沿确实省节点，但每次状态比较要扫 `cap`（长度 `h`）和 `rel`，常数吃掉了收益。**这个「凸包」在 n≤16、S≤4 的状态格上不划算**，默认关闭；它只在状态更稠密（例如同 `mask` 有大量不同 `cap`）时才可能回本，本轮没有这样的实例。

### 5.8 合成紧状态：OS 会输 1000×，探针是必要的

随机生成 400 个 `n=11–16`、`m=3–4` 的实例，用精确引擎二分出 `OPT`，保留 `S=OPT−1−cp ∈ [0,4]` 的 45 个：

|---|---:|---:|

| 判决 | 全 NO | 全 NO |
| OS 胜 CPS 的例数 | — | **0/45** |

这些实例的链很短（`L=1–5`，`L/n=0.091–0.385`），CPS 的 placement 少、residual 也小；OS 要在十几个自由任务上枚举序，立刻爆炸。**`L/n` 不能当分类器**：合成集 0.091–0.385，5 个残例 0.31–0.40，完全重叠。能分类的是成本本身：CPS 在这 50 个状态上是双峰的——45 个 ≤54 节点，5 个 ≥16,810 节点，中间有 300× 的空隙。**探针 300 落在这个空隙里，50/50 分类正确**（这是在这 50 个状态上的测量，不是普遍保证）。

这与命题 2 的反例一致：聚合容量看不见资格。**门里必须保留全资格**；异资格下 `OS=NO` 仍可靠（容量松弛的 NO 是真 NO），`OS=YES` 一律降级为 unknown。

### 5.10 并行：一个结构性坏消息

OS 的序树在根上只有 **1** 个孩子（这些 DAG 都是单源，任务 0 是唯一 ready），深度 2 有 2–5 个节点，深度 3 才有 6–23 个：

```text
idx 5 : 宽度 1, 1, 2, 6, 12, 17, 28, 35, ...
idx 21: 宽度 1, 1, 5, 23, 58, 95, 123, 182, ...
idx 42: 宽度 1, 1, 5, 22, 47, 60, 82, 114, ...
```

根切分的 list-scheduling 上界是 `4/(1+4·D/W)`，而 `D/W≈1`，上界 0.8——**没有并行度**。要并行只能在深度 3 切（宽度 6–23），前 3 层串行；本轮没有实现。v2.2 的 PAR-CPS 4 核 1.98× 在 OS 上没有直接对应物：这是 16× 串行收益的代价，必须写清楚。

### 5.11 消融与退化

| 变体 | held-out 50 | 5 残例节点 | 说明 |
|---|---:|---:|---|
| v2.2（CPS） | 3.480 s | 110,971 | 基线 |
| HY（默认） | **1.552 s** | 8,307 | 探针+OS |

## 6. 负结果与陷阱

### 6.1 OS 不支配 CPS

45 个合成紧状态上 OS 0/45 胜，29/45 撞 10k cap。任何「用 OS 替换 CPS」的方案都会在这些状态上慢 10–1000×。这是本轮最重要的负结果，也是 HY 存在的理由。

### 6.2 探针只在双峰时成立

300 这个数来自「CPS 在 50 个状态上 ≤54 或 ≥16,810」。如果 CPS 的成本分布是连续的（例如 2,000 节点），探针会误判：要么把便宜的 CPS 打断去跑 OS，要么在 OS 上浪费 10k。**探针是经验参数，不是定理。**

### 6.3 序不变性只对「无学习」成立

定理 2 的前提是精确 memo、无跨状态学习。如果将来加 clause learning / backjumping，顺序就会影响学到的子句，随机重启可能重新有用。本轮没有学习，所以 SA 被排除；这不等于 SA 永远无用。

### 6.4 支配前沿不划算

省 4.5% 节点、多 67% 时间。状态格太稀疏。见 §5.7。

### 6.5 异资格 YES 失真

6/8 的 `h=OPT` YES 不可验证，1 个假 YES。门必须保留；`OS=NO` 仍可靠。

### 6.6 根层没有并行度

深度 1 宽度 1，`D/W≈1`。PAR-OS 需要深度 3 的切分，未实现。

### 6.7 OS 的 YES 依赖全资格 + 区间染色

`OS=YES` 的排程验证用独立检查器（按起点做精确机器分配的回溯）；全资格下由区间图性质保证成功，异资格下会失败（实测 6/8）。

### 6.8 `est/q/A` 必须精确

与 v2.2 相同：高估 `est/q/A` 会让 OS 假 NO；低估只会更弱。这是继承的规格。

### 6.9 实现陷阱

- `EARLIEST` 的区间是半开 `[t,t+p)`；容量数组长度 `h`，越界要显式截断。
- memo 键必须含 `rel` 的**剩余任务**分量；只含 `mask` 会把不同窗口合并成假 NO。
- 撞 `N_OS` 必须是 UNKNOWN，不能当 NO。
- `rel` 只在**已排前驱**完成后更新；不要把未排前驱的 `est` 混进去。
- 序树证书的检查器要自己重算 `cap/rel`，不能信 payload。
- 探针的预算是**全局**的；按 placement 各给 300 会让 5 个残例各烧 7×300。

### 6.10 没有形式化验证

400 组暴力 + 70 张 YES 排程 + 45 组合成 + 4 个异资格 NO 复核，是很强的证据，但不是 Coq/Lean。定理 1–5、引理 1–2 是纸面证明 + 可重放内核。

## 8. 已知风险

1. **探针是经验参数**：300 只在「CPS 双峰」的 50 个状态上验证过；成本连续时分类会错，收益反转。
2. **OS 不支配 CPS**：合成集 0/45 胜，29/45 撞 cap；不能把 OS 当默认引擎。
3. **OS 的完备性依赖 active schedule 定理 + 全资格**：异资格 YES 失真 6/8，有 1 个假 YES。
4. **序不变性只对无学习成立**：加学习后 SA 可能重新有用，本轮没测。
5. **没有短证书**：OS 的证书是序树重放，大小 6,802（5 例），不是 LP/对偶那种 `O(n)`。
6. **根层无并行**：`D/W≈1`，PAR-CPS 的 1.98× 没有对应物。
7. **前沿不划算**：省 4.5% 节点、多 67% 时间。
8. **`est/q/A` 精确性**：高估会假 NO，继承规格。
9. **公共期限**：各自期限 `d_i` 的路径未实现。
10. **门的覆盖率**：`S≤4`、`n≤16`、depth 0；更松的紧实例不触发。
11. **时间**：held-out 3.480→1.552 s；38/deep 不变；easy/planted 未重跑（门不触发，逐字不变）。
12. **没有形式化验证**：纸面证明 + 随机/半穷举 + 重放。

---

## 9. 一句话最大风险

**这一轮的 16× 不是来自一个更聪明的算法，而是来自一次「坐标系换对了」的测量：active schedule 定理只在全资格、窗口精确、整数时间下成立，而 OS 在合成短链紧状态上又会输给 CPS 1000×——所以真正的算法其实是那个 300 节点的探针，探针一旦选错（CPS 成本不再双峰），全部收益立刻反转。**
