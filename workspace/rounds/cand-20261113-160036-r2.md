# 第 67 轮（承接第 66 轮「BATON 电池感知工具编排」IP-224~233；本轮灵感：「工具调用」×「轻量化设计」）

> 第 66 轮把「一次性证书」升级为「可保管的安全储备」，其自述的最大风险同样锋利：**BATON 引入了一个未被管理的管理者**——漂移率、磨损系数、独立性证书、Q_guard/OI 阈值全靠离线标定；一旦这个健康模型偏乐观，系统就会「以为自己还有电，其实已经没电」，而自我确信只是把第 65 轮的单点故障换成一个更精致、更难察觉的元层级单点故障。第 67 轮不再给 BATON 再加一层管理，而是反过来做减法：**把整套安全栈拆成「一个可穷举验证的可信小核」与「一组按需调用、可缓存、可蒸馏、可早停、永不放宽包络的非可信重工具」**。本轮核心命题是：
>
> **安全只押在「小到可以验证的核」与「默认拒绝」上；性能恢复才交给工具。工具调用从「调用更多」变成「在正确的时刻调用最少的工具，并验证返回」；轻量化不是省算力，而是把可信计算基（TCB）、假设债务与攻击面一起压到帕累托前沿。**

## 0. 直觉与动机

**灵感 1（工具调用 → 少调用、晚调用、验证后调用）**
直觉：LLM agent 工程里最危险的不是「工具选错」，而是**对陈旧/幻觉结果的成功返回**——schema 合法、HTTP 200，但结果是过期缓存或错误版本，系统却当真理继续推理。第 66 轮的 PCP 已经识别了 `stale_success`，但仍默认「工具应当常驻、应当都调用」。真正的工具调用纪律是四条：(i) **最小权限**——工具只能读它声明需要的证据，不能顺手读全局语义；(ii) **能力令牌**——没有 `cap` 就不许触碰实时安全路径；(iii) **默认拒绝**——没有可信证据就不动，而不是「没证据所以随便动」；(iv) **有界重试 + 回退 + 幂等**——重试必须有预算，失败必须能退到更保守的工具。于是本轮把每个技能/探针/估计器/健康模型都当成**可调用的外部工具**，并追问：这一次调用到底值不值得？

**灵感 2（轻量化设计 → 三个层次的「轻」）**
直觉：轻量化不只是模型压缩。它有三层：
- **结构轻**：最小可信计算基（TCB）。航空与安全关键系统的常识是——**能被形式化验证的只有很小的核**；大的、学习的、语义的组件必须被排除在 TCB 之外，否则「验证」只是口号。Saltzer–Schroeder 的「经济机制 / 最小权限 / 默认拒绝 / 完全中介」在这里逐条对应。
- **计算轻**：蒸馏、量化、剪枝、缓存、早停、充分统计。安全判定往往只需要**一个标量裕度**，不需要重建整个世界。
- **认知轻**：Occam / MDL——**更少的假设意味着更少的失效模式**。每加一个模型就多一份「假设债务」；组件不是越多越安全，过度堆叠会扩大攻击面与共因风险。航空的 MEL（最低设备清单）也说明：不是所有设备都必须常开，但必须**明确哪些不可延后、哪些可以降级**。

**灵感 3（合流 → LITHE：Lightweight Invocation-gated Toolkit with Hardened Envelope，可信小核 × 惰性重工具）**
闭环：**CORE** 维护无学习、固定开销、可穷举验证的硬包络与默认拒绝 → **TCG** 给每个工具以能力令牌、输入输出契约、假设足迹、健全性证书与失效模式 → **LIR** 只在「预期信息价值 > 调用代价」时惰性调用重工具 → **COMPOSE** 用契约传播与假设冲突检测组合工具链 → **OCCAM** 以假设债务与 MDL 剪掉「不付租金」的组件 → **SSC** 把证据压成决策充分统计量 → **ANY** 用任意时间上下界做早停 → **CACHE** 用带有效性域的缓存/蒸馏/量化加速 → **RED** 把冗余分成「不可压缩的物理冗余」与「可压缩的计算冗余」并给出降级阶梯 → **J_lithe** 审计「为什么只调用这些工具、为什么现在可信」。第 66 轮的管理者本身也是工具，也要被验证、被降级、被预算约束。

**灵感 4（直接补第 66 轮的洞：把管理者也变成非可信工具）**
BATON 的病根是「健康模型既当裁判又当运动员」：它决定还能不能继续，却没人验证它自己。LITHE 的处理是：(i) 健康模型只是**元工具**，带独立的物理 oracle（已知负载、温升、称重、库仑重置）；(ii) 它只能影响**性能档位**（多久再接地、用多重的工具），**不能修改硬包络，也不能解除默认拒绝**；(iii) oracle 不通过 → 立即降级为最坏情况调度（更频繁充电、更低力限、只跑 CORE），而不是相信它；(iv) 它自己也有假设债务，也进 Occam 预算。这样「以为自己还有电」最多导致**过早停机**，不能直接变成执行许可。

**灵感 5（代价与张力：轻量会删冗余，冗余是单点故障的解药）**
必须诚实：轻量化天生与冗余对立。于是把冗余分层——**物理冗余 P（独立急停、看门狗、硬断电、关键量的独立第二通道）不可压缩**，它是 CORE 可验证性的前提；**计算冗余 C（集成、多世界模型、全 FIR、全证书）可以压缩/缓存/蒸馏**，因为它的失效只降低性能，不越过硬包络。轻量不是「越小越好」，而是在（安全裕度、性能、算力、假设债务）四目标上选**帕累托前沿**；过度堆叠（第 66 轮）与过度裁剪（裸核）都是次优。

## 1. 形式化定义（增量：定义 249–264）

- **定义 249（LITHE 闭环）**：LITHE = (BATON, CORE, TCG, LIR, OCCAM, SSC, ANY, CACHE, COMPOSE, RED, J_lithe)。定位：BATON 的「可信小核 + 惰性重工具」重构。不变式：**(I1) CORE 常驻、无学习、开销有界，每个动作执行前强制；(I2) 任何工具都不能修改硬包络与实时安全路径，只能在包络内工作；(I3) 未通过健全性/溯源/新鲜度的结果降级为 advisory，不改变不确定集；(I4) 轻量化只压缩计算冗余 C，不压缩物理冗余 P；(I5) 实时流只做 CORE、轻量校验、扣减与切断，零学习写。**
- **定义 250（常驻安全核 CORE）**：CORE = (H_core, W, L_stop, µ, fail_safe)。H_core(x) 为**不可逆物理伤害包络**（硬件力/速度/能量上限、停止距离、可达域、独立断电），由经验证的互锁与看门狗实现；W 为看门狗，L_stop 为停止距离约束，µ 为默认拒绝策略。要求：∀x∈X_abs, u∈H_core(x)：B_core(x,u)≥0 可在有界状态抽象上穷举/区间验证。CORE 不读归因、不读视觉语义、不做学习推理；无证书时执行 safe-idle/制动。**CORE 只保证「不造成不可逆物理伤害」，不保证任务成功；任务级安全由健全的工具链负责。**
- **定义 251（工具能力契约 TCG）**：工具 τ=(id, cap, need, provide, A_τ, snd_τ, cost_τ, fail_τ, idem_τ, rollback_τ, att_τ)。`cap` 为能力令牌；`need⊆Signals` 为它**被允许读取**的最小证据集（最小权限）；`provide` 为带类型的输出；A_τ 为假设足迹；snd_τ 为健全性证书（区间/共形/物理 oracle）或 ⊥；cost_τ 为时间/能量/磨损/风险；fail_τ 为失效模式；idem/rollback 决定重试语义；att_τ 为结果溯源要求。**snd_τ=⊥ 的工具是 advisory：可以提议，但不得收缩不确定集、不得绕过 CORE。**
- **定义 252（不确定集、健全性与保证格）**：隐藏状态/参数 x∈X；U⊆X 是**健全上近似**当且仅当 x_true∈U。序 U₁⊑U₂ ⇔ U₁⊆U₂（越小的 U 知识越强）。认证动作集 E(U)={u∈H_core : ∀x∈U, safe_task(x,u)}。若 U₁⊆U₂ 则 E(U₁)⊇E(U₂)。认证工具做 U←U∩U_τ；**仅当 snd_τ 有效且 att_τ 通过**才允许，健全性保证 x_true∈U∩U_τ。advisory 工具只产生候选，不改变 U。安全不变式：**实际派发的 u∈H_core 且（u∈E(U_current) 或 u=safe_idle）**。
- **定义 253（惰性调用与 EVOI 门控 LIR）**：默认不调用重工具。在当前 U 下候选调用 a 的期望信息价值
  EVOI(a)=E[ |E(U)|−|E(U∩U_a)| ]（或折算为期望任务代价下降）− c(a)，
  调用当且仅当 EVOI(a)/(c_time+λ_e c_energy+λ_w c_wear) ≥ 1、预算足够、且 att 可用；否则跳过。**「没有收益就不调用」是轻量的第一性原理**；EVOI 用廉价代理估计，该代理本身也是元工具（定义 260），其不确定性保守计入。
- **定义 254（假设债务与 MDL / OCCAM）**：工具集 S 的假设足迹 A(S)=∪_τ A_τ，债务
  D(S)=Σ_{α∈A(S)} w_α + λ_c·log|Θ_S|（Θ_S 为模型复杂度，MDL）。
  失效风险上界 p_unsound(S) ≤ Σ_{α∈A(S)} p_α + p_model。Occam 选择
  S*=argmin_S [E[执行代价]+λ_R·R(S)+λ_D·D(S)]，s.t. E(U_S)⊇E_req。
  若某工具带来的认证体积增益/单位（代价+债务）<ε，则剪除。**组件不是越多越安全：过度堆叠会因假设重叠与共因扩大攻击面。**
- **定义 255（决策充分统计证书 SSC）**：对动作 a，安全判定只依赖最坏裕度 m_a(U)=min_{x∈U} margin(x,a)。统计量 T 是**决策充分**的，若对所有决策域内的 U 有 sign(m_a(U))=sign(m_a(T(U)))。证书 C_a=(T(U), bound, proof) 只需证明 T 是 m_a 的健全下界（区间/Lipschitz/共形），**无需重建 U**。近似 T̂ 带误差 ε 时用 m̂−ε；仅当 m̂−ε≥0 才认证。压缩率 CR=|U|/|C_a|，决策无损或有界。
- **定义 256（任意时间裕度 ANY）**：任意时间估计器在 t 次运算后给出 m_t^L≤m_a(U)≤m_t^U，满足 m_t^L 单调不减、m_t^U 单调不增。早停规则：m_t^L≥0 → 接受；m_t^U<0 → 拒绝；预算耗尽 → 拒绝（默认拒绝）。证书记录 t、m_t^L、m_t^U。**截断计算只会更保守，绝不会过度认证。**
- **定义 257（缓存/蒸馏/量化 CACHE）**：缓存条目 c=(result, provenance, validity_region V_c, t_obs, calib_id)。仅当当前状态∈V_c 且新鲜度有效才可复用；分布漂移时 V_c 单调收缩。蒸馏学生 f̃ 带认证误差 ε_d（在标定域上 |f̃−f|≤ε_d）；量化用区间 [q^L,q^U] 做保守算术。缓存/近似结果只有在 snd 证书覆盖时才可认证，否则一律 advisory。
- **定义 258（组合代数 COMPOSE）**：链 τ₁→…→τ_n。接口契约：provide(τ_i) ⊨ need(τ_{i+1})，否则记接口失配失效 f_iface。若每段健全且假设可满足（A_i∪A_j 无矛盾），则组合健全，债务 D=ΣD_i+D_iface，失效模式 F=∪F_i∪{f_iface}。若 D>D_max、存在假设冲突、或共享同一失灵支撑（假独立），则拒绝该链并回退到更短链/CORE。**组合不是免费的：接口与假设冲突是新的失效模式。**
- **定义 259（冗余分层与降级阶梯 RED）**：冗余分两类：P（物理、不可压缩：独立急停、看门狗、硬断电、关键量独立第二通道，|P|≥p_min）与 C（计算、可压缩：集成、多模型、全 FIR、全证书）。轻量化只允许剪 C。降级阶梯 ℓ=0..4（0 仅 CORE，1 +缓存，2 +蒸馏/量化，3 +全认证工具，4 +主动探针），认证集
  E^{(0)}=E(U_core) ⊆ E^{(1)} ⊆ … ⊆ Safe_true，
  阶梯只增加性能，不改变安全集；低储备/高债务自动降档，最终 ℓ=0。
- **定义 260（元工具与独立 oracle）**：任何用于**调度或门控其它工具**的模型（健康模型、SoC/SoH、漂移估计、EVOI 代理）都是元工具 τ_M，带自己的 A、D、snd 与独立物理 oracle O_M（已知负载、温升、称重、库仑重置）。验证谓词 |τ_M(s)−O_M(s)|≤ε_M 且 O_M 与 τ_M 的失效支撑不相交。验证失败或 oracle 不可用 → τ_M 降级，策略退回最坏情况调度（更频繁再接地、更低 Q_guard、仅 CORE）。**元工具永远不能解除默认拒绝，也不能修改 P 层。**
- **定义 261（假设冲突与共因检测）**：若 A(S) 含 α 与 ¬α，或两工具在同一上下文要求互斥前置条件，则 S 不可容许；丢弃低优先级工具或回退。若两个自称独立的工具共享同一标定、同一训练分布或同一物理通道，则判为**假独立**，其共因风险并入第 66 轮 independence_cert 的上界，不得用于 2-of-n。
- **定义 262（安全-轻量帕累托）**：工具集 S 的画像 (ρ(S),P(S),C(S),D(S))，分别为安全裕度、性能、期望代价、假设债务。S 支配 S' 当且仅当四项均不劣且至少一项严格优。LITHE 在约束 C≤B、D≤D_max、ρ≥ρ_req 下按**字典序「安全→性能→代价→债务」**选帕累托点。**「轻」= 在安全约束下最小充分，而非绝对最小。**
- **定义 263（LITHE 证书 J_lithe）**：J_lithe=(J_baton, core_hash, core_ver, tool_chain, cap_grants, assumption_debt, snd_certs, ssc_hash, anytime_bound, cache_freshness, degrade_level, meta_oracle_ver)。Valid ⇔ Valid(J_baton) ∧ CORE 版本已验证 ∧ 每个认证工具 snd/att 有效 ∧ D≤D_max ∧ 实际动作∈H_core ∧（advisory-only ⇒ 未收缩 U）∧ P 层在线 ∧（元工具已验证或已保守降级）∧ 阶梯档位与预算一致。
- **定义 264（LITHE 闭环算子）**：语义流 [BATON 语义流 → CORE 初始化 U_core → TCG 能力匹配 → LIR EVOI 门控 → 调用认证工具并验 att → COMPOSE 链/冲突检测 → OCCAM 剪枝与债务校验 → SSC 压缩 → ANY 早停 → RED 选档 → J_lithe]；实时流 [CORE 硬包络与默认拒绝 → 轻量 att/新鲜度校验 → 缓存化 EVOI 决策 → 派发 → 元 oracle 监控 → 切断]。

## 2. 关键算法骨架

```python
# CORE：常驻、无学习、每个动作强制（实时）
def core_guard(x, u):
    if u is None or not in_hard_envelope(x, u):     # H_core，硬件/互锁
        return SAFE_IDLE
    if not watchdog_ok() or not p_layer_alive():     # P 层冗余
        return EMERGENCY_STOP
    return u                                         # 只做钳制，不做语义推理

# TCG + LIR：能力校验 + 惰性调用（语义流决策，实时只读缓存）
def maybe_invoke(tool, ctx, U, budget, D_left):
    if not (tool.cap in ctx.grant and set(tool.need) <= ctx.signals): return None
    if tool.snd is None or not attest(tool, ctx):     # 非认证工具 → advisory
        return tool.propose(ctx)
    evoi = expected_certified_volume_gain(U, tool) - tool.cost.total()
    if evoi <= 0 or tool.cost.total() > budget or tool.debt > D_left:
        return None                                   # 不调用就是最优
    return tool.run(ctx)                              # 返回 U∩U_tau

# SSC + ANY：只压裕度，不重建世界；早停只会更保守
def certify_action(a, U, budget_ops):
    L, Ubd = -inf, +inf
    for t in range(budget_ops):
        L = max(L, margin_lower_bound(a, U, t))
        Ubd = min(Ubd, margin_upper_bound(a, U, t))
        if L >= 0: return ACCEPT, (L, Ubd, t)
        if Ubd < 0: return REJECT, (L, Ubd, t)
    return REJECT, (L, Ubd, budget_ops)               # 默认拒绝

# OCCAM：假设债务 vs 认证增益；过度堆叠是次优
def prune_tools(S, E_req, B, D_max):
    S = sorted(S, key=lambda t: t.unit_gain, reverse=True)
    keep = []
    for t in S:
        trial = keep + [t]
        if debt(trial) <= D_max and gain_per_debt(trial, E_req) >= EPS:
            keep = trial
    return keep

# RED：只剪计算冗余，物理冗余保底
def degradation_level(post, Q, D, budget):
    l = 4
    while l > 0 and (min(Q) < Q_guard[l] or D > D_max[l] or budget < cost(l)):
        l -= 1
    return l                                          # 0 = 仅 CORE / safe-idle
```

## 3. 保证概要与推导要点（完整推导见产物区）

- **引理 11（小核可验证性）**：在有限/有界状态抽象上，CORE 的验证代价 ~|X_abs|·|U|；把学习/语义/归因组件排除出 TCB 后，需要形式化验证的代码与状态空间大幅缩小，验证覆盖率可达。因此「核足够小」不是审美，而是**可证明性的前提**；大组件只能作为非关键工具。
- **引理 12（健全精化与组合保序）**：若 x_true∈U 且 snd_τ 有效，则 x_true∈U∩U_τ；故精化保持健全、E 单调不减；advisory 不改变 U。组合链在无假设冲突/接口失配时保持健全，冲突时拒绝。**这是「工具只恢复性能、不放宽安全」的形式化依据。**
- **定理 11（LITHE 端到端：物理安全不依赖重工具与元模型）**：在 A95 下——(i) CORE 硬包络经互锁验证且每动作强制；(ii) 只有带有效 snd/att 的工具能收缩 U，且 D≤D_max；(iii) advisory 与元工具不能改变 U、不能绕过 CORE、不能解除默认拒绝；(iv) P 层在线；(v) 无认证即 safe-idle——则**任何执行都不越出不可逆物理伤害包络 H_core，无论重工具、缓存、健康模型或归因是否正确**。任务级安全 = 「由健全链认证的动作」或「不动作」；唯一残余风险是**错误的健全性证书**本身。
- **定理 12（复杂度-安全帕累托与过度堆叠的次优性）**：设工具数 n 的认证收益 b(n) 凹增（边际递减），风险 r(n)=r₀+ρn²（假设重叠/共因随 n 超线性增长），代价 c·n。则总目标 J(n)=c n+λ_R r(n)−µ b(n) 在有限 n* 处最优；第 66 轮「全部常驻」（n=n_max）只是一般点，通常被 n*<n_max 支配。**轻量化由此有了定量最优，而不是工程口号。**
- **命题（缓存/蒸馏的安全加速）**：若缓存有效性域与新鲜度成立、蒸馏误差 ε_d 进入保守下界，则近似工具与教师给出相同接受/拒绝决策的概率 ≥1−α，加速比 ≈ 教师代价/学生代价；一旦 att/新鲜度失败即降级为 advisory，安全不受影响。
- **实时性**：CORE 钳制+看门狗 <0.05ms，轻量 att/新鲜度 <0.1ms，缓存化 EVOI 查表 <0.01ms；TCG/COMPOSE/OCCAM/SSC/ANY 全在语义流，实时路径在 BATON 的 ≈2.5ms 内不增反降（重工具默认不调用）。

## 2. 形式化定义（完整版）

**定义 249（LITHE 闭环）** LITHE 是 BATON 的「可信小核 + 惰性重工具」重构：保留 BATON 的资源与健康元管理，但把其常驻安全职责收窄到 CORE；把 VISTA/BATON 的归因、世界模型、健康估计、探针、全证书全部降级为带能力契约的**非可信工具**，由 LIR 按需调用、OCCAM 按假设债务剪枝、SSC/ANY 压缩与早停、COMPOSE 组合、RED 降级。不变式：
(I1) CORE 常驻、无学习、固定开销，每个动作执行前强制；
(I2) 任何工具都不能修改 `H_core` 与实时安全路径，只能在包络内工作；
(I3) 未通过 `snd/att` 的结果降级为 advisory，不改变 `U`；
(I4) 轻量化只压缩计算冗余 C，不压缩物理冗余 P；
(I5) 实时流只做 CORE、轻量校验、扣减与切断，零学习写。

**定义 250（常驻安全核 CORE）** CORE=(H_core, W, L_stop, µ, fail_safe)。`H_core(x)` 由硬件互锁与经验证的固定逻辑实现，包含力/速度/能量上限、停止距离、可达域、独立断电；`W` 为看门狗与心跳；`L_stop` 为基于实测速度的停止距离约束；`µ` 为**默认拒绝**策略：无有效认证时只输出 `safe_idle` 或制动。要求在有界状态抽象 `X_abs` 上
∀x∈X_abs, u∈H_core(x): B_core(x,u)≥0
可穷举或区间验证。CORE **不读归因、不读视觉语义、不做学习推理**。CORE 只保证「不发生不可逆物理伤害」，不保证任务成功；任务级安全由健全的工具链负责（定理 11 明确区分两者）。

**定义 251（工具能力契约 TCG）** 工具 τ=(id,cap,need,provide,A_τ,snd_τ,cost_τ,fail_τ,idem_τ,rollback_τ,att_τ)。`cap` 为能力令牌，`need⊆Signals` 为最小可读证据集（最小权限），`provide` 为带类型的输出，`A_τ` 为假设足迹，`snd_τ` 为健全性证书或 ⊥，`cost_τ=(c_time,c_energy,c_wear,c_risk)`，`fail_τ` 为失效模式集合，`idem/rollback` 规定重试与回滚，`att_τ` 规定结果溯源（tool_id/version/arg_hash/t_obs/calib_id/cert_hash/nonce）。调用 κ 合法 ⇔ `cap∈ctx.grant ∧ args⊨Σ_in ∧ need⊆ctx.signals ∧ pre_τ`。**snd_τ=⊥ 为 advisory：可提议，但不得收缩 U、不得绕过 CORE、不得用于证书。** 这把第 66 轮的 TIC 从「契约 + 预算」推进到「能力 + 健全性 + 最小权限」。

**定义 252（不确定集、健全性与保证格）** 隐藏状态/参数 x∈X。`U⊆X` 是健全上近似 ⇔ `x_true∈U`。序 `U₁⊑U₂ ⇔ U₁⊆U₂`。认证动作集 `E(U)={u∈H_core : ∀x∈U, safe_task(x,u)}`。由定义，`U₁⊆U₂ ⇒ E(U₁)⊇E(U₂)`。认证工具做 `U←U∩U_τ`，**仅当 snd_τ 有效且 att_τ 通过**；健全性保证 `x_true∈U∩U_τ`。advisory 工具只产生候选，不改变 U。安全不变式：
**实际派发 u∈H_core，且（u∈E(U_current) 或 u=safe_idle）。**
注意 `E(U)` 是任务级认证，`H_core` 是物理级硬包络；工具只能在 `H_core` 内提升任务可用性，永不放宽物理包络。

**定义 253（惰性调用与 EVOI 门控 LIR）** 默认不调用重工具。在当前 U 下候选调用 a 的期望信息价值
`EVOI(a)=E[|E(U∩U_a)|−|E(U)|]·v − Δcost(a)`（v 为把认证体积折算为任务收益的系数），
调用当且仅当
`EVOI(a)/(c_time+λ_e c_energy+λ_w c_wear) ≥ 1`、预算足够、且 att 可用；
否则跳过并保持在 CORE/当前档位。EVOI 由廉价代理估计（本身是元工具，其不确定性保守计入，定义 260）。这是**最优停止/背包**的特例：由于信息增益在 U 上近似次模、调用代价可加，贪心策略相对最优的遗憾有界（当代理校准）。**「没有收益就不调用」是轻量的第一性原理。**

**定义 254（假设债务与 MDL / OCCAM）** 工具集 S 的假设足迹 `A(S)=∪_τ A_τ`，债务
`D(S)=Σ_{α∈A(S)} w_α + λ_c·log|Θ_S|`（Θ_S 为模型复杂度，MDL）。
失效风险上界 `p_unsound(S) ≤ Σ_{α∈A(S)} p_α + p_model`。Occam 选择
`S*=argmin_S [E[执行代价]+λ_R·R(S)+λ_D·D(S)]`，s.t. `E(U_S)⊇E_req`，其中 `R(S)∝p_unsound(S)·impact`。
剪枝规则：若工具 τ 的认证体积增益/单位（代价+债务）<ε，则剪除。
**组件不是越多越安全**：假设重叠会放大共因风险，模型复杂度会放大分布漂移风险；第 66 轮「全部常驻」只是一般点（见定理 12）。

**定义 255（决策充分统计证书 SSC）** 对动作 a，安全判定只依赖 `m_a(U)=min_{x∈U} margin(x,a)`。统计量 T 是**决策充分**的，若对所有决策域内的 U 有 `sign(m_a(U))=sign(m_a(T(U)))`。证书 `C_a=(T(U),bound,proof)` 只需证明 T 是 `m_a` 的健全下界（区间算术 / Lipschitz / 共形 / 物理不等式），**无需存储或重建 U**。近似 `T̂` 带误差 ε 时用 `m̂−ε`；仅当 `m̂−ε≥0` 才认证。压缩率 `CR=|U|/|C_a|`。证书是**动作特定**的：为 a 压缩不会自动服务 a′，这正是轻量的取舍。

**定义 256（任意时间裕度 ANY）** 任意时间估计器在 t 次运算后给出
`m_t^L ≤ m_a(U) ≤ m_t^U`，`m_t^L` 单调不减、`m_t^U` 单调不增，且 `m_t^L↑m_a`、`m_t^U↓m_a`。
早停：`m_t^L≥0` → 接受；`m_t^U<0` → 拒绝；预算耗尽 → 拒绝（默认拒绝）。证书记录 `(t,m_t^L,m_t^U)`。**截断计算只会更保守，绝不会过度认证**——这是把「算力预算」纳入安全论证的关键。

**定义 257（缓存/蒸馏/量化 CACHE）** 缓存条目 `c=(result,provenance,validity_region V_c,t_obs,calib_id)`；仅当当前状态∈V_c 且 `t_now−t_obs≤τ_fresh` 且 calib 未过期才可复用；分布漂移检测（残差分位数偏移）使 `V_c` 单调收缩。蒸馏学生 `f̃` 带认证误差 `ε_d`（标定域上 `|f̃−f|≤ε_d`）；量化用区间 `[q^L,q^U]` 做保守算术。缓存/近似结果**只有被 snd 证书覆盖时才可认证**，否则一律 advisory。这把第 66 轮「新鲜度」推进到「近似也有误差条」。

**定义 258（组合代数 COMPOSE）** 链 `τ₁→…→τ_n`。接口契约：`provide(τ_i) ⊨ need(τ_{i+1})`，否则记接口失配失效 `f_iface`。若每段健全且 `A_i∪A_j` 可满足，则组合健全，`D=ΣD_i+D_iface`，`F=∪F_i∪{f_iface}`。若 `D>D_max`、存在假设冲突（α 与 ¬α）、或两工具共享失灵支撑（假独立），则拒绝该链并回退到更短链/CORE。**组合不是免费的：接口与假设冲突是新的失效模式**，这与第 66 轮共因热传播同构。

**定义 259（冗余分层与降级阶梯 RED）** 冗余分两类：
- **P（物理、不可压缩）**：独立急停、看门狗、硬断电、关键量的独立第二物理通道；要求 `|P|≥p_min`（如独立急停 ≥2 路）。P 是 CORE 可验证性的前提，轻量化**禁止**剪 P。
- **C（计算、可压缩）**：集成、多世界模型、全 FIR、全证书、多探针；可缓存/蒸馏/剪枝。
降级阶梯 `ℓ=0..4`（0 仅 CORE，1 +缓存，2 +蒸馏/量化，3 +全认证工具，4 +主动探针），认证集
`E^{(0)}=E(U_core) ⊆ E^{(1)} ⊆ … ⊆ Safe_true`，
阶梯只增加性能，不改变安全集。低储备/高债务/低预算自动降档，最终 `ℓ=0` 只跑 CORE + safe-idle。

**定义 260（元工具与独立 oracle）** 任何用于调度或门控其它工具的模型（健康模型、SoC/SoH、漂移估计、EVOI 代理）都是元工具 `τ_M`，带自己的 `A_M、D_M、snd_M` 与**独立物理 oracle** `O_M`（已知负载、温升、称重、库仑重置、独立计时）。验证谓词：
`|τ_M(s)−O_M(s)|≤ε_M` 且 `F(τ_M)∩F(O_M)=∅`（oracle 与元工具失效支撑不相交）。
验证失败或 oracle 不可用 → `τ_M` 降级，策略退回最坏情况调度（更频繁再接地、更低 Q_guard、更低力限、仅 CORE）。**元工具永远不能解除默认拒绝，也不能修改 P 层。** 这是对第 66 轮「未被管理的管理者」的直接结构性回答：管理者也要过 oracle，也要有债务，也只能收紧。

**定义 261（假设冲突与共因检测）** 若 `A(S)` 含 α 与 ¬α，或两工具在同一上下文要求互斥前置条件，则 S 不可容许；丢弃低优先级工具或回退。若两个自称独立的工具共享同一标定、同一训练分布、同一物理通道或同一 OOD 源，则判为**假独立**；其共因风险并入第 66 轮 `independence_cert` 的上界，不得用于 2-of-n。这把第 66 轮的独立性审计推进到**工具组合层**。

**定义 262（安全-轻量帕累托）** 工具集 S 的画像 `(ρ(S),P(S),C(S),D(S))`，分别为安全裕度、性能、期望代价、假设债务。S 支配 S′ 当且仅当四项均不劣且至少一项严格优。LITHE 在 `C≤B、D≤D_max、ρ≥ρ_req` 下按**字典序「安全→性能→代价→债务」**选帕累托点。**「轻」= 在安全约束下最小充分，而非绝对最小**；过度堆叠（BATON）与过度裁剪（裸核）都在前沿之外。

**定义 263（LITHE 证书 J_lithe）** `J_lithe=(J_baton, core_hash, core_ver, tool_chain, cap_grants, assumption_debt, snd_certs, ssc_hash, anytime_bound, cache_freshness, degrade_level, meta_oracle_ver)`。验证：
`Valid(J_lithe) ⇔ Valid(J_baton)`
∧ CORE 版本已验证
∧ 每个认证工具 `snd/att` 有效
∧ `D≤D_max`
∧ 实际动作 ∈ `H_core`
∧（advisory-only ⇒ 未收缩 U）
∧ P 层在线且 `|P|≥p_min`
∧（元工具已验证 或 已保守降级）
∧ 阶梯档位与预算/储备一致。
审计链新增：为什么只调用这些工具（tool_chain + EVOI）、凭什么相信它们（snd_certs/att）、一共背了多少假设（assumption_debt）、为何只算到这里（anytime_bound）、物理冗余是否还在（P 层）。

**定义 264（LITHE 闭环算子）** 语义流：
[BATON 语义流 → CORE 初始化 `U_core` → TCG 能力匹配 → LIR EVOI 门控 → 调用认证工具并验 att → COMPOSE 链/冲突检测 → OCCAM 剪枝与债务校验 → SSC 压缩 → ANY 早停 → RED 选档 → J_lithe]；
实时流：
[CORE 硬包络与默认拒绝 → 轻量 att/新鲜度校验 → 缓存化 EVOI 决策 → 派发 → 元 oracle 监控 → 切断]。

### IP-234 CORE：可信小核（实时，无学习）

```python
class Core:
    """最小可信计算基。只做物理硬包络、看门狗、默认拒绝。
       绝不读取 post/vision/attribution，绝不学习。"""
    def __init__(self, H_core, p_layer, limits, watchdog):
        self.H, self.P, self.lim, self.wd = H_core, p_layer, limits, watchdog

    def guard(self, x, u):
        if u is None:
            return SAFE_IDLE                       # 默认拒绝
        if not self.wd.ok() or len(self.P.alive()) < self.P.p_min:
            return EMERGENCY_STOP                  # P 层冗余失效即停
        if not self.H.contains(x, u):             # 硬件力/速/能/停止距离/可达域
            return SAFE_IDLE
        return u

    def verify(self, X_abs, U_abs):
        # 有界抽象上的穷举/区间验证：∀x,u: B_core≥0
        return all(self.H.margin(x, u) >= 0
                   for x in X_abs for u in U_abs)
```

```python
def assumption_debt(S, w_alpha, lam_c):
    A = set().union(*(t.A for t in S))
    complexity = sum(t.model_bits for t in S)
    return sum(w_alpha[a] for a in A) + lam_c * np.log1p(complexity)

def prune_tools(S, E_req, B, D_max, eps=0.05):
    # 按单位增益排序，贪心保留「付得起租金」的工具
    S = sorted(S, key=lambda t: t.unit_gain, reverse=True)
    keep = []
    for t in S:
        trial = keep + [t]
        if assumption_debt(trial, W_ALPHA, LAM_C) > D_max:
            continue
        if marginal_gain(trial, E_req) / (t.cost.total() + t.debt + 1e-9) < eps:
            continue
        keep = trial
    return keep

def choose_toolset(candidates, E_req, B, D_max):
```

### IP-238/239 SSC + ANY：充分统计与早停

```python
def sufficient_margin(a, U):
    # 只计算最坏裕度及一个可验证下界；不重建 U
    m = min(task_margin(a, x) for x in sample_cover(U))   # 覆盖采样
    proof = interval_certificate(a, U)                    # 区间/Lipschitz 证明
    return SigStat(value=m, bound=proof.lower, proof=proof)

def certify_anytime(a, U, budget_ops):
    L, Ub = -np.inf, np.inf
    for t in range(1, budget_ops + 1):
        L = max(L, margin_lower_bound(a, U, t))           # 单调不减
        Ub = min(Ub, margin_upper_bound(a, U, t))         # 单调不增
        if L >= 0:
            return ACCEPT, (t, L, Ub)
        if Ub < 0:
            return REJECT, (t, L, Ub)
    return REJECT, (budget_ops, L, Ub)                    # 默认拒绝
```

### IP-241 COMPOSE：组合代数

```python
def compose(chain, ctx, D_left):
    U = ctx.U_core
    D = 0.0
    F = set()
    for i, t in enumerate(chain):
        if i > 0 and not provides(chain[i-1], t.need):
            return None, 'interface_mismatch'             # f_iface
        if conflicts(chain[:i+1]):
            return None, 'assumption_conflict'
        if false_independence(chain[:i+1]):
            return None, 'shared_failure_support'
        D += t.debt + (DEBT_IFACE if i > 0 else 0.0)
        if D > D_left:
            return None, 'debt_budget'
        r = maybe_invoke(t, ctx, U, ctx.budget, D_left - D)
        F |= t.fail
        if r is None or r.kind != 'certify':
            return None, 'not_certified'                  # 只允许认证链作业
        U = r.U                                      # 健全精化
    return U, 'ok'
```

## 4. 推导

**引理 11（小核可验证性）** 设 CORE 的状态抽象为 `X_abs`、动作抽象为 `U_abs`。穷举验证代价为 `O(|X_abs|·|U_abs|)`，区间验证代价为 `O(#constraints·#boxes)`。若把学习模型、语义感知、归因、世界模型全部排除出 TCB，则 `|X_abs|` 只含物理量（位置、速度、力、能量、停止距离）与看门狗状态，规模与任务语义无关，验证可覆盖。反之，若 TCB 含高维学习组件，`|X_abs|` 随感知分辨率指数增长，验证覆盖率不可保证。故「核足够小」是可证明性的前提，而非工程偏好。∎

**引理 12（健全精化与组合的保序性）** 设 `x_true∈U` 且 snd_τ 有效，则 `x_true∈U_τ`，故 `x_true∈U∩U_τ`，精化保持健全。由 `E` 对 U 的反单调性，`U∩U_τ⊆U ⇒ E(U∩U_τ)⊇E(U)`，即工具只能扩张**任务认证集**、不能扩张物理包络 `H_core`。链式组合在每段 snd 有效且接口/假设一致时归纳保持健全；若存在假设冲突或接口失配，`U_true` 不再保证落在组合结果的模型中，故必须拒绝。advisory 工具不改变 U，故对 `E` 与 `H_core` 无影响。∎

**定理 11（LITHE 端到端：物理安全不依赖重工具与元模型）** 设在 A95 下：
(A95-1) CORE 的 `H_core` 经互锁/区间验证，且每个派发动作前强制执行；
(A95-2) 只有带有效 `snd/att` 的工具能收缩 U，且 `D≤D_max`；
(A95-3) advisory 与元工具不能改变 U、不能绕过 CORE、不能解除默认拒绝；
(A95-4) P 层在线且 `|P|≥p_min`；
(A95-5) 无认证动作时只输出 `safe_idle/制动`。
则对任意执行轨迹，物理状态不越出不可逆伤害包络 `H_core`，**无论重工具、缓存、蒸馏、健康模型或 FIR 归因是否正确**。
证明要点：(1) 每个动作都过 `CORE.guard`，故 `u∈H_core` 或 `u=safe_idle`；(2) 工具失效/陈旧/未认证 → 降级 advisory 或跳过，最多使 `E(U)` 变小，导致更多 safe-idle，而非更危险动作；(3) 元工具失效 → 保守调度，只影响性能档位；(4) 默认拒绝保证「不知道就不动」；(5) 因此第 66 轮「健康模型偏乐观→继续执行」的因果链在 LITHE 中被 CORE + 默认拒绝 + 元 oracle 切断。**任务级安全**仍依赖健全链：若链的 snd 证书错误，则可能认证一个任务上不安全的动作；这是定理 11 明确保留的残余风险（见第 7 节风险 1）。∎

**定理 12（复杂度-安全帕累托与过度堆叠的次优性）** 设工具数 n 的任务收益 `b(n)` 凹增（边际递减，`b′>0,b″<0`），风险 `r(n)=r₀+ρn²`（假设重叠/共因/攻击面随 n 超线性增长），代价 `c·n`。总目标
`J(n)=c n + λ_R(r₀+ρn²) − µ b(n)`。
`J′(n)=c+2λ_Rρn−µb′(n)`，`J″(n)=2λ_Rρ−µb″(n)>0`（因 `b″<0`），故 J 严格凸，存在唯一有限最优 `n*`（若 `J′(0)<0`），否则 `n*=0`。第 66 轮的「全部常驻」对应 `n=n_max`，一般情况下 `n*<n_max`，即过度堆叠被 `n*` 支配：多出来的工具只增加假设债务与共因风险，边际性能收益不足以补偿。轻量化由此获得定量最优，而非审美选择。∎

**命题（缓存/蒸馏的安全加速）** 设教师工具 `f`、学生 `f̃` 在标定域上 `|f̃−f|≤ε_d`，缓存条目在有效域 `V_c` 内结果精确、在域外不复用。则用 `m̂−ε_d` 作为裕度下界的认证满足：`m̂−ε_d≤m≤m̂+ε_d`，故 `ACCEPT` 蕴含真实裕度 `m≥0`（保守），不会过度认证。若缓存/蒸馏/量化结果未被 snd 覆盖或 att 失败，则降级 advisory，认证集退回上一档。加速比的上界为 `E[c_teacher]/E[c_student]`，缓存命中率 `h` 时进一步乘 `1/(1−h)`。∎

**命题（EVOI 门控的遗憾界）** 若 EVOI 代理校准（估计误差 ≤δ）、各工具信息增益次模、代价可加，则按 `EVOI/cost` 贪心调用相对最优调用序列的期望收益遗憾 ≤ `(1−1/e)·OPT + δ·|S|`。故「少调用」不是保守到无能：在代理校准时它接近最优；代理失准时由定义 260 降级为保守默认，性能下降但安全不变。∎

**正确性定理（LITHE-Complete）** 见定理 11：核心是**把第 66 轮「安全依赖健康模型/归因正确」彻底替换为「安全依赖经过验证的小核 + 默认拒绝 + P 层物理冗余」**；重工具、缓存、蒸馏、健康模型全部降级为非可信性能组件，只能恢复性能、不能放宽安全。定理 12 进一步说明为什么「少而对的工具集」通常优于「多而全的常驻栈」。

## 7. 已知风险

**一句话**：LITHE 把安全押在「**我们正确判断了什么是本质的**」与「**健全性证书本身可信**」上——一个被错误裁剪的常驻核（漏掉一个真实危害维度），或一份在分布漂移下失准的共形/区间证书，会让系统在**没有任何重工具被调用**的情况下自信地安全；而被轻量化删掉的计算冗余，恰恰是原本能发现这个裁剪错误的证据。这是「默认拒绝 + 最小核」所依赖的隐藏假设 A95：**核的边界选对了，且 snd 证书不会与核共享同一个未知失效源。**

**次级风险与缓解**：
1. **健全性证书本身是新的单点**：共形在分布漂移下失准、区间模型漏掉未建模动力学；缓解：证书必须绑定标定域与版本，漂移检测触发重标定；对 snd 证书自身做交叉验证（两套独立区间方法），失败即降级为 advisory。
2. **核裁剪错误（漏掉危害维度）**：这是最危险的「沉默错误」；缓解：CORE 只裁到「不可逆物理伤害」这一可验证维度，不裁任务语义；用 FMEA/HAZOP 维护危害清单；保留 P 层独立急停；定期红队注入未列危害，测「默认拒绝」是否生效。
3. **默认拒绝导致可用性崩塌**：工具全部失效时只剩 safe-idle；缓解：RED 阶梯 + 缓存/蒸馏保底，优先保证「不危险」再逐步恢复；任务层允许人工接管。
4. **假设债务难以量化**：w_α/p_α 是人工设定；缓解：用历史失效事件回标，给乐观先验加保守上界；对共享标定/共享训练分布的工具自动合并假设，避免「假独立」低债。
5. **蒸馏/量化在长尾失效**：ε_d 只在标定域成立；缓解：有效性域外直接拒绝，不做外推；长尾样本进红队集定期重标。
6. **工具组合爆炸**：链式组合的假设与接口组合数大；缓解：类型系统 + 假设代数做静态拒绝，限制链长，优先组合已验证的短链。
7. **EVOI 代理失真**：代理本身是学习模型，可能低估/高估价值；缓解：代理纳入元工具 oracle，定期用真实收益回归校准；失真时退回保守调度（少调用）。
8. **物理冗余 P 被工程成本侵蚀**：为减重可能想删第二急停；缓解：`|P|≥p_min` 写进硬不变式与 J_lithe，任何工具/策略无权修改；P 的失效支撑必须与 CORE 独立。
9. **「轻」被误读为「省掉验证」**：轻量化的收益来自可验证性，不是省掉验证；缓解：CORE 验证与 snd 证书是准入条件，不是可选项；J_lithe 无 core_ver 即拒。

## 8. 与前序轮次的关系（承接性说明）

- **第 64 轮 GRIP**：几何可证伪。LITHE 不改其证书语义，只把其中重型组件移出 TCB。
- **第 65 轮 VISTA**：故障可归因。LITHE 把 FIR/AFA/WCV-V 等全部降级为惰性工具，归因不再是执行许可。
- **第 66 轮 BATON**：资源与健康元管理。LITHE 把 BATON 的管理层拆成「CORE + 元工具」：健康模型只能调性能档，不能解除默认拒绝；电池/健康模型自身也要过独立 oracle。
- **本轮 LITHE**：把「一次性证书 / 可保管资源」进一步变成「**可信小核 + 最小充分工具调用**」。安全性的最终依赖从「归因正确 / 健康模型准确」转为「**CORE 硬包络可验证 + 默认拒绝 + P 层物理冗余 + snd 证书健全**」这四个不依赖具体故障类型的条件；代价是当工具失效或证书不可信时，系统会更早、更频繁地停在 safe-idle——**用可用性换可证明性**。
