# 第 41 轮 · 二灵感落地 v18：躯干辅助全身控制 × 末端位姿合同（「位姿合同」横切层 Π-Plane，四层架构 v6）

> 承接第 40 轮（v17：热预算治理 × 步数感知规划 × 学习-TO 混合轨迹）。本轮灵感词「全身控制 / 末端位姿」。先给出本轮最重要、也最反直觉的实证结论：我对官方公开的 4 个 G1_Dex1 v3.0 数据集、**1,592 episodes / 530,654 帧**做了逐帧审计（脚本与结果见产物区 §1 与 `exp/wbc_pose_audit.py`）——(1) **底盘几乎从不移动**：`action.base_command` 的 vx/vy/wz 仅在 **0.023%** 的帧非零；(2) **末端位姿目标与下一帧实际位姿之间存在稳定的系统性偏移**：左臂 z 向 **+10.78mm**、右臂 **+13.25mm**，去掉常量后仍有 7.37/8.44mm 动态残差；而**关节命令的跟踪误差只有 0.91/1.07°**；(3) 腰的活动范围只有 yaw 5.7–9.8°、roll 2.3–6.4°、pitch 4.5–9.3°，下肢 12 关节只是 8–23° 的平衡姿态摆动。这三条把 v17 的盲区钉死了：v17 的 IP-50 在「末端位姿/关节参考」上做 TO 精修，却默认 EE 目标与实际到达位姿是同一个坐标系、同一个量；同时在「全身」上默认底盘可用。**v18 的主轴因此不是「加一个全身控制器」，而是：把全身控制收窄为「躯干辅助的位姿可行性管理」，把末端位姿升格为一份必须校准、可验证、带容差的「合同」**——新增 Π-Plane（位姿合同平面），与 v17 的 Δ-Plane（资源平面）正交。

## 0. 实证核实（先事实后推理；继承 F59–F66，新增自采审计 E1–E8，口径 2026-11-10）

- **继承事实**：F59 榜单=平均成功率+步骤分；F60 官方 `PolicyService` 观测含双臂关节 [7]×2、双臂 EE 位姿 [6]×2（gripper_base 系）、lower_body [15]；动作含 joint/ee 互斥、夹爪、`pivot [7]`；§6 记录每步时延与动作统计规律性；F61 32 个 `G1_Dex1_*` LeRobot 数据集公开（v3.0，30fps，头部双目+双腕）；F62 UnifoLM 模型族与 G1 硬件；F63–F65 热管理/图世界模型/VLA 效率谱系；F66 榜单未发布、「榜首<30%」为假说（A34）。
- **E1（样本）**：v3.0 的 ZipUp / Stack_Block / Unlock / HangCup 四个真实任务，**1,592 episodes / 530,654 帧**；每帧同时含 action 与下一帧 observation，可做「命令→实际」残差辨识。
- **E2（底盘）**：`action.base_command` 的 vx/vy/wz 非零帧占比逐任务 **0.016%–0.032%**（合计 0.023%）；pivot 的 xyz 分量非零帧同样仅 0.016%–0.032%，height 稳定在约 0.723–0.739m（std ≤0.03）。→ 这不是移动操作；**底盘不是常规控制自由度**。
- **E3（腰与下肢）**：`waist_state_joint` 活动范围 yaw 5.7–9.8°、roll 2.3–6.4°、pitch 4.5–9.3°；下肢 12 关节 8–23° 的姿态摆动。→ 全身控制真实的操作面是**腰 3 DoF**；下肢是**稳定性观测**，不是指令通道。
- **E4（位姿偏移）**：`action.*_ee_pose_gripper_base(t)` 与 `observation.state.*_ee_pose_gripper_base(t+1)` 的差：左 z **+10.78mm**、右 z **+13.25mm**（逐 episode 均值标准差 2–3mm，跨 4 任务稳定），x/y 近 0；去常量后残差 **7.37/8.44mm**（跨任务 p95 15–27mm）。最优动作滞后 **k=2–3 帧（67–100ms）**。→ action 是短时域目标，不是当前位姿；EE 目标不能直接当执行量。
- **E5（关节跟踪）**：`action.*_arm(t)` 与 `observation.state.*_arm(t+1)` 的逐关节绝对误差仅 **0.91/1.07°**（p95 2.4–3.3°）。→ **关节通道的跟踪远好于 EE 目标通道**。
- **E6（动态残差）**：去常量偏移后，残差随运动速度单调上升：静止/低速帧 **4.1–7.2mm**，高速帧 **10.8–17.2mm**。→ 残差 = **常量目标偏移 + 速度相关滞后**；精密释放/插入前必须「停稳」。
- **E7（冗余贡献）**：用 14 个臂关节增量线性解释左 EE 位置增量，**R²=0.886**；加入腰 3 DoF 只到 **0.894**（+0.8pp）。→ 腰不是 EE 运动的主贡献者，它的价值在可达性/可操作度/约束满足，而非精度主项。
- **E8（通道诚实）**：EE 位姿是 `recomputed_ee_valid=1.0` 的重算量（FK），不是独立外部测量；因此 E4 是「目标约定 vs FK 实现」的差，不是传感器噪声。数据集存在 v1/v3 两种 schema（旧 schema 用 `observation.left_ee/action.left_ee/body`）；对旧 schema 的 Erase_Board / Fold_Towel 抽查，偏移只有 **-1.15/-4.34mm** 与 **-2.29/+0.12mm**——**偏移是 schema/任务相关的，不能写死一个常数**（登记 A51）。

## 1. 研究者直觉（先直觉与动机，后形式化）

**直觉 1（全身控制 → 先证明它有多小，再决定做多大）**。我原以为这个赛道最值得做的是「移动底盘 + 双臂」的全身控制：用底盘扩展工作空间、用腰补偿姿态、用下肢稳定重心。但 E2/E3 把这个想象按在地上摩擦：底盘在 99.98% 的帧里被命令为零，腰只有 5–10° 的活动量，下肢只是平衡摆动。也就是说，**官方的「全身」不是 locomotion，而是「站定 + 腰微调 + 手臂主操作」**。这不是坏消息——它反而把问题从「造一个昂贵的全身 MPC」缩小成一个**可验证的 17-DoF 冗余分配问题**：14 个臂关节做主任务，3 个腰关节在零空间里换可操作度/可达性/双臂协同，12 个下肢关节只作为平衡约束的观测。v17 的 IP-50 把 pivot 当「准静态」处理，方向对，但缺了**平衡约束、可操作度余量、以及「腰只在有增益时才动」的准入**。这一轮要把这块补成 IP-51。

**直觉 2（末端位姿 → 它不是动作，是合同）**。E4/E5 是整轮最刺眼的一对数字：EE 目标与下一帧实际位姿差 1 厘米级，而关节命令只差 1 度级。这意味着官方接口里**「末端位姿」是一个规划/约定的量，不是控制执行量**；真正被忠实执行的是关节目标。v17 的 IP-50 直接优化 EE 参考并假设跟踪模型精确，这会把一个**系统性 1 厘米偏移**当成噪声塞进 TO 的目标里——在放置公差只有几毫米的任务上，这足以判死刑。正确做法是把 EE 位姿做成一份**合同** `C=(T^des, ε, Σ, b, μ, feasible, settle, fallback)`：先校准 `b`（目标约定偏移），再检查 `feasible`（可达/可操作度/碰撞/平衡），再要求 `settle`（停稳后残差达标），最后才允许执行。这样「末端位姿」同时服务规划（IP-49）、TO（IP-50）、执行（IP-43/T-WBC）与失败监测（IP-24），成为一层薄而关键的横切。

**直觉 3（两词的接缝：在位姿里规划，在关节里执行，在位姿里验收）**。E5 说关节跟踪好，E4 说 EE 目标有偏移——这两条合起来给了一个非常干净的架构分工：**plan in pose, execute in joint, verify in pose**。规划器与 TO 用 EE 位姿思考（任务语义、容差、可行性）；T-WBC 把校准后的位姿合同逆解成关节/腰命令（利用更好的跟踪）；下一帧再用观测 EE 位姿回写残差与合同状态（验收与漂移监测）。这比「端到端 EE 回归」更可解释，也比「纯关节回归」更接近评测语义。Π-Plane 就是这条接缝的载体。

**直觉 4（腰的正确用法：买余量，不买位移）**。E7 说腰只解释 0.8pp 的 EE 运动方差——如果我用腰去「多走一点」，几乎一定是浪费。但腰可以买三样别的东西：(a) **可操作度余量**——把手臂从接近奇异/接近限位的地方拉回高可操作度区；(b) **可达性**——远目标先用腰/身高补一点，避免手臂过伸；(c) **双臂相对位姿**——双手协调时用腰做共同的姿态基底，减少两臂互相打架。所以 T-WBC 的腰不是「第二组手臂」，而是**约束满足的零空间资源**：只有当 `μ`（可操作度余量）或关节限位距离低于阈值时才动用，且动用量与热/步数预算挂钩（喂 IP-48/IP-49）。这条「最小充分」原则也是本轮对 v17「能力最大化」的再次纠偏。

**直觉 5（修剪：单本体 + 底盘几乎不动，砍掉两片幻想）**。v17 仍背着跨本体运动（IP-42）、物理增广（IP-26）、任务代数 ⊕/⁻¹（IP-47）。E1–E3 一照就清楚：(a) 只有单一 G1/Dex1，32 个数据集同本体，跨本体对测试零价值；(b) 物理增广依赖未核实的 URDF（A17），而公开 32 任务已覆盖物体/场景多样性；(c) 32 个桌面任务以序列为主，⊕/⁻¹ 的组合语义对步骤分贡献很低。**本轮把这三项降级 P2，把复杂度预算让给「位姿合同 + 躯干辅助」两条线**——按规则 51，这是「深化」而不是「砍」。

## 2. 灵感词 → 落地线（新增 + 重构 + 修剪登记）

- 「**全身控制**」→ **IP-51 TORSO-WBC（P0 新增，重构 IP-39/50 的执行侧）**：17-DoF（14 臂 + 3 腰）层级 QP；EE 位姿主任务、双臂相对位姿次任务、CoM/ZMP 支撑多边形硬约束（用 `lower_body` 观测）、关节限位/自碰撞/可操作度约束；腰只在可操作度/限位/双臂协同余量不足时准入；底盘默认固定，仅「例外重定位」预算内可用；权重含力矩/热（喂 IP-48）。
- 「**末端位姿**」→ **IP-52 POSE-CONTRACT（P0 新增，重构 IP-50 的目标侧）**：`C=(T^des, ε, Σ, b, μ, feasible, settle, fallback)`；公开数据离线辨识 `b`（常量偏移 + 构型相关项）、在线准静态 EWMA 更新；`feasible`=可达/可操作度/碰撞/平衡四查；`settle`=按 E6 速度-残差曲线的停稳判据；位姿残差监视器兼作失败早期信号；消费方=IP-49/50/43/24/33。
- **横切**：**Π-Plane（位姿合同平面）**——每个进入机器人执行的位姿目标都必须携带 `C`；不允许未校准的解析 EE 目标直接下发。它与 Δ-Plane 正交：Δ 管资源，Π 管位姿。
- 升级：**IP-50**（TO 目标改为校准后的位姿合同；执行经 T-WBC；deadline 不变）、**IP-49**（`p_s` 乘 `P(feasible)`；步数成本加 `c_pivot + c_settle`）、**IP-48**（腰/底盘动作入热账；零空间力矩最小化）、**IP-39**（waypoint 以位姿合同形式下发）、**IP-36**（语义图增工作空间/可达包络与支撑面）、**IP-33**（增位姿/工作空间 CBF）、**IP-24**（增位姿残差/偏移漂移失败签名）、**IP-25/46**（可行性证书并入 SLO/证书）、**IP-21**（旗舰改为「位姿合同」级联）。
- 修剪登记：**IP-42 跨本体 → P2**（单一人形 G1/Dex1，零测试价值）；**IP-26 物理增广轴 → P2**（依赖 A17 URDF，公开 32 任务已覆盖多样性）；**IP-47 ⊕/⁻¹ 任务代数 → P2**（桌面任务以序列为主，组合语义对步骤分贡献低）。

## 3. 形式化直觉（严格版见产物区 §3）

**定义 29（控制相关全身模型）**：`q=(q_arm^L, q_arm^R, q_waist)∈R^17` 为可控自由度；`q_stance∈R^12` 为下肢平衡姿态（观测，不指令）；`p=(vx,vy,wz,height)∈R^4` 为 pivot 的常规子空间。因 E2 实测 `vx=vy=wz≈0`，把 `p` 的平移/转向视为**例外动作**（emergency repositioning，需预算与理由），默认 `p=p0` 固定。末端位姿 `T_i(q)=FK_i(q_arm^i, q_waist)`，`i∈{L,R}`。

**定义 30（躯干辅助全身控制 T-WBC）**：层级 QP（lexicographic）
```
min_{q̇,δ} ½‖q̇‖²_W + ½‖δ‖²
s.t.  J_i(q) q̇ = Δξ_i^des + δ_i        (EE 主任务，最高优先)
      J_rel(q) q̇ = Δξ_rel^des           (双臂相对位姿，次优先)
      CoM(q,q_stance) ∈ S, ZMP(q,q_stance) ∈ S   (支撑多边形硬约束)
      q ∈ [q_min,q_max], q̇ ∈ [q̇_min,q̇_max]
      d_self(q) ≥ ε, w(q) ≥ w_min, |q_waist| ≤ q_waist,max
```
`W` 含力矩/热权重（喂 IP-48）。**关键**：不是让 17 个关节都去追一个位姿，而是在满足平衡与安全约束的零空间里，用腰去换可操作度、可达性与双臂协同；腰的动用量由 `μ`（可操作度余量）与限位距离的**准入阈值**决定（最小充分原则）。

**定义 31（位姿合同）**：`C_i=(T_i^des, ε_i, Σ_i, b_i(q,σ), μ_i, feasible_i, settle_i, fallback_i)`
- `b_i = E[log(T_i^obs(t+1) ⊖ T_i^cmd(t)) | q, σ]`：校准偏移（常量 + 构型项），离线从公开数据辨识，运行时只在准静态帧用 EWMA 更新；
- `μ_i = w(q*)/w_ref`：可操作度余量（Yoshikawa 度量归一化）；
- `feasible_i = 1[∃q∈Q_adm: e(T_i^des⊖b_i, T_i(q)) ≤ ε_i ∧ w(q)≥w_min ∧ d_self≥ε]`；
- `settle_i`：精密事件（抓取/释放/插入/交接）前的停稳判据；
- 执行命令：EE 通道用 `T_i^cmd = T_i^des ⊖ b_i`；joint 通道经 T-WBC 逆解为 `(q_arm, q_waist)`。
**合同三查**：可执行（feasible）、可停稳（settle 后残差 ≤ ε）、可验证（下一帧观测位姿在容差内）。任一不过按 `fallback` 降级：调腰 → 调 pivot（预算内）→ 重规划 → 退化为关节伺服。

**定义 32（位姿残差模型与停稳协议）**：`r_t = log(T_obs(t+1) ⊖ T_cmd(t)) = b_0 + J_b(q)θ + Λ(q̇) + ε_t`，其中 `Λ` 为速度相关滞后（E6）。停稳协议：在 release/insert 前保持 `T_cmd`，直到连续 `n_settle` 帧 `‖r_t − b_0‖ ≤ ε_i` 且 `‖q̇‖ ≤ q̇_settle`；否则继续等（计入步数预算）。这给精密操作一个**可观测的完成判据**，而不是靠固定延时。

**定义 33（位姿可行性感知的得分）**：在 IP-49 的 `E_score(π)=Π_s p_s(s|σ)·g(N)−λP(fail)` 中，`p_s` 乘以 `P(feasible_i(C))`，步数成本加入 `c_pivot·1[使用 pivot] + c_settle·n_settle`；即「不可达/不可停稳的计划」在规划期就被折价，而不是执行到失败再重试。

## 4. 关键决断

1. **先测量再设计**：全身控制收窄为 14 臂 + 3 腰；底盘默认固定、例外才动；下肢只做平衡约束观测。这是 E2/E3 直接给出的边界。
2. **位姿即合同**：任何解析 EE 目标必须携带校准 `b`、容差 `ε`、可行性 `feasible`、停稳 `settle`；未校准目标不得下发。这是 E4/E5 的直接推论。
3. **规划在位姿、执行在关节、验收在位姿**：利用关节通道更好的跟踪（E5），但用位姿通道做任务语义与验收；T-WBC 是两者之间的桥。
4. **腰买余量不买位移**：腰只在可操作度/限位/双臂协同余量不足时准入；动用量入热账与步数账（E7）。
5. **修剪三项**：跨本体、物理增广、任务代数降 P2——把复杂度预算让给位姿合同与躯干辅助。

## 5. 本轮最大风险（一句话）

**全身自由度在本赛题里可能小到「腰只是 5–10° 的微调」，而 1 厘米级的 EE 偏移可能只是公开数据集 v3.0 的记录约定（旧 schema 仅 -1~-4mm），未必等于评测端控制器的真实约定——若 T-WBC 无增益、且位姿校准在提交接口上不可复现，「躯干辅助 + 位姿合同」就会退化成两个只在离线数据上成立的机制；必须以 E73（32 任务位姿残差全审计）+ E74（T-WBC vs 臂-only）+ E75（位姿校准 A/B）+ E76（可行性证书早判）+ E77（底盘/腰预算）+ E78（端到端）六重守门，按「位姿校准 > 腰辅助 > 底盘例外」优先序保底，全败即回退 v17。**

# 第 41 轮产物 · 创新点清单 v18：躯干辅助全身控制 × 末端位姿合同（「位姿合同」横切层 Π-Plane，四层架构 v6）

> 承接 v17（第 40 轮：热预算治理 × 步数感知规划 × 学习-TO 混合轨迹）。本轮灵感词「全身控制 / 末端位姿」。与 v17 不同，本轮先做了一次**对公开数据集的逐帧审计**（4 个 v3.0 真实任务、1,592 episodes、530,654 帧；`exp/wbc_pose_audit.py`，结果 `exp/wbc_pose_audit_results.json`），再据此改写问题设定：官方「全身」不是移动操作——底盘命令非零帧仅 **0.023%**，腰只有 5–10° 活动量，下肢只是平衡姿态；官方「末端位姿」不是可直接执行的控制量——EE 目标与下一帧实际位姿存在 **+10.78/+13.25mm** 的稳定 z 偏移，而关节命令跟踪误差仅 **0.91/1.07°**。v17 的盲区因此被精确定位：IP-50 的 TO 在未校准的 EE 参考上追求毫米级精度，IP-39/50 把 pivot 当准静态而缺平衡/可操作度约束。v18 新增 **2 项核心 IP（IP-51 TORSO-WBC / IP-52 POSE-CONTRACT）+ 1 个横切平面（Π-Plane：位姿合同平面）**，升级 10 项协作 IP，**修剪 3 项 v17 过度设计（IP-42 / IP-26 / IP-47 ⊕/⁻¹ → P2）**。主轴从「单机交付物理学」推进到「**位姿合同学**」：先证明全身自由度有多小、再决定用多少；先校准末端位姿、再谈精度。

## 0. 结论

- **Π-Plane（位姿合同平面，本轮总纲）**：任何进入机器人执行的 EE 目标都必须携带 `C=(T^des, ε, Σ, b, μ, feasible, settle, fallback)`；未校准的解析 EE 目标不得直接下发。它与 v17 的 Δ-Plane 正交（Δ 管热/时延/步数，Π 管位姿）。
- **IP-51 TORSO-WBC（P0 新增）**：17-DoF（14 臂 + 3 腰）层级 QP；EE 位姿主任务、双臂相对位姿次任务、CoM/ZMP 支撑多边形硬约束（`lower_body` 观测）、关节限位/自碰撞/可操作度约束；腰只在可操作度/限位/双臂协同余量不足时准入；底盘默认固定、仅「例外重定位」预算内可用；`W` 含力矩/热权重（喂 IP-48）。
- **IP-52 POSE-CONTRACT（P0 新增）**：公开数据离线辨识 `b`（常量 + 构型项）、在线准静态 EWMA；`feasible` 四查（可达/可操作度/碰撞/平衡）；`settle` 按速度-残差曲线；位姿残差监视器兼作失败早期信号；消费方=IP-49/50/43/24/33。
- **修剪（规则 51/55）**：IP-42 跨本体→P2（单一人形 G1/Dex1）；IP-26 物理增广轴→P2（依赖 A17 URDF，32 任务已覆盖多样性）；IP-47 ⊕/⁻¹→P2（桌面任务以序列为主）。**P0 核心 IP 收敛为 5 项：IP-48/49/50/51/52。**
- **关键实证**：底盘非零 **0.023%**；EE z 偏移 左 **+10.78mm** / 右 **+13.25mm**；去常量残差 **7.37/8.44mm**；关节误差 **0.91/1.07°**；EE 增量方差 R²：臂 0.886 → 臂+腰 0.894（腰仅 +0.8pp）；最优动作滞后 2–3 帧。
- **通道诚实**：EE 位姿是 `recomputed_ee_valid=1.0` 的 FK 重算量而非独立外部测量（E8）；v1/v3 schema 的偏移不同（旧 schema -1~-4mm，A51）；URDF 未核实（A17）；「榜首<30%」为假说（A34）；N 值未公布（A36）。
- **行动项**：A16–A50 延续；**A51–A56 新增**（schema 相关偏移、腰/底盘真实权限、提交端 EE 约定、URDF 可得性、平衡支撑面参数、停稳阈值标定）。

### 3.2 IP-52 POSE-CONTRACT（末端位姿合同，本轮核心）

**IP 卡片（六字段）**：
- **动机**：E4 证明官方 action 的 EE 目标与下一帧实际位姿存在稳定 +10.78/+13.25mm z 偏移；E5 证明关节命令跟踪仅 0.91/1.07°；E6 证明残差随速度上升；E8 证明 EE 是 FK 重算量、且偏移随 schema 变化。v17 的 IP-50 在未校准 EE 参考上做 TO，会把系统偏差当成目标误差，直接吃掉毫米级精度收益。
- **与现有方案差异**：现有 VLA/TO 默认「下发 EE 目标 = 到达该位姿」；数据驱动策略靠行为克隆隐式吸收偏移。**我们显式把偏移、可行性、停稳、残差监视做成一份可验证的合同**，让解析规划器/TO/执行器/失败监测共享同一套位姿语义；这是「位姿作为接口」而非「位姿作为动作」。
- **技术可行性**：偏移辨识只需公开数据的 action/observation 对（离线、无真机）；可行性四查在 17-DoF 上毫秒级；在线 EWMA 只在准静态帧更新，计算 <0.1ms；无需新模型。
- **所需资源**：数据=32 个公开数据集（离线）；算力=IK/QP <1ms；接口=F60 的 joint/ee 通道 + `lower_body`；URDF（A17，缺失时可退化）。
- **落地步骤**：① E73 全 32 任务 + v1/v3 schema 偏移审计；② 拟合 `b_0 + J_b(q)θ`；③ 实现可行性四查（IK/可操作度/碰撞/平衡）；④ 实现停稳协议与残差监视；⑤ 接入 IP-49/50/51/24/33；⑥ E75/E76 验收。
- **风险**：偏移是数据集日志约定而非评测约定（→E75 在提交接口上复核；失败则退回关节空间执行）；可行性证书误报（→阈值校准 + fallback 不阻塞）；停稳吃步数（→只在精密事件前启用）；schema 漂移（→ schema-aware 校准）。

**符号表**：

| 符号 | 含义 | 来源/取值 |
|---|---|---|
| `T_i^des` | 期望 EE 位姿（base 系） | IP-39/IP-50 |
| `b_i` | 目标-实现偏移 | 离线拟合 + 在线 EWMA；E4 初始 ≈ 左 +10.8mm、右 +13.3mm（z） |
| `ε_i` | 位姿容差（位置/姿态） | 任务/相位配置；放置类更紧 |
| `Σ_i` | 位姿不确定性 | VLA/TO/感知协方差 |
| `μ_i` | 可操作度余量 | `w(q*)/w_ref`，Yoshikawa |
| `feasible_i` | 可行性标志 | 四查结果 |
| `settle_i` | 停稳标志 | 连续 `n_settle` 帧残差 ≤ ε 且 `‖q̇‖` 小 |
| `fallback_i` | 降级链 | 调腰 → 调 pivot → 重规划 → 关节伺服 |

**算法**：
```
输入：位姿目标 T^des（来自 IP-39/50）、当前 q、lower_body、schema σ、任务/相位
1. 校准：b ← load_offline_bias(task, σ);  if 准静态: b ← EWMA(b, r_t)
2. 可行性四查：
     q* ← IK(T^des ⊖ b, seed=q, waist∈[q_min,q_max])
     feasible ← (‖log(T^des⊖b ⊖ FK(q*))‖ ≤ ε)
                ∧ (w(q*) ≥ w_min) ∧ (d_self(q*) ≥ ε_self)
                ∧ (CoM(q*,q_stance) ∈ S)
3. 若 not feasible：按 fallback 链尝试
     a) 腰增量 Δq_w（求解最小 ‖Δq_w‖ 使 feasible 或 μ↑）
     b) pivot 例外重定位（预算内，计入 c_pivot）
     c) 重规划（IP-49）
     d) 退化为 arm-only 关节伺服
4. 精密事件前：settle 协议
     while not (连续 n_settle 帧 ‖r_t−b‖≤ε ∧ ‖q̇‖≤q̇_settle):
         保持 T^cmd（计入 c_settle·步数）；超预算则上报 IP-24
5. 下发：EE 通道输出 T^cmd=T^des⊖b；joint 通道输出 T-WBC 解 (q_arm,q_waist)
6. 监视：r_t = log(T_obs(t+1) ⊖ T_cmd(t))
     |r_t − b| > θ_resid → IP-24 失败签名（偏移漂移/碰撞/打滑）
返回：命令 + 合同状态 C（供 IP-49/50/51/24/33）
```
**复杂度**：IK/QP 17-DoF <1ms；可行性四查 <1ms；在线 EWMA O(6)；总开销 <2ms/次，远低于 chunk 窗口。

**正确性论证**：
- **P61（偏移校正的期望误差下降）**：设 `r = b + Λ(q̇) + ε`。若 `b` 的估计误差为 `δ_b`，则下发 `T^cmd = T^des ⊖ b̂` 后在准静态（`Λ≈0`）下的期望误差满足 `E‖r−b̂‖ ≤ ‖δ_b‖ + E‖ε‖`；而下发 `T^des` 的误差满足 `E‖r‖ ≤ ‖b‖ + E‖ε‖`。E4/E6 给出 `‖b‖≈12mm`、去常量残差≈7–8mm，故准静态下期望误差可降 **≈35–45%**（由 E75 验证）。
- **P62（可行性的可靠性）**：若 `feasible=0`，则不存在满足位姿容差且安全/平衡的 `q`，执行该目标必然产生 ≥ε 的位姿误差或约束违反；因此 `feasible=0` 是「需要重规划/调腰」的**可靠（sound）但不完备**信号。它可能漏报（保守 IK 失败），但不会把不可行说成可行（在 `Q_adm` 与 `w_min` 定义准确的前提下）。
- **P63（停稳的充分条件）**：由 E6，`Λ(q̇)→0` 当 `‖q̇‖→0`；若停稳判据满足 `‖r_t−b‖≤ε`，则合同容差在**观测上**已达成。故 settle 是「可观测的完成判据」，不依赖固定延时；代价是步数，需与 IP-49 的 `c_settle` 权衡。
- **P64（最小充分腰准入）**：若腰准入阈值为 `μ<μ_min ∨ d_lim<d_min ∨ 双臂相对位姿误差>ε_rel`，则当三者均满足时 T-WBC 的零空间把腰拉回姿态先验，不改变 EE 主任务解；因此腰不会在非必要情形下引入额外运动/热/步数。E7 的 +0.8pp 方差贡献支持「腰不是主贡献者」的定位。

### 3.3 IP-51 TORSO-WBC（躯干辅助全身控制，本轮核心）

**IP 卡片（六字段）**：
- **动机**：E2/E3 证明底盘几乎不动、腰只有 5–10°、下肢是平衡姿态；v17 的 IP-50 把 pivot 当准静态，缺平衡约束与可操作度管理；末端精度失败的一部分来自「手臂接近奇异/限位/过伸」，而不是最后 5mm 的控制精度。
- **与现有方案差异**：经典 WBC 面向腿式/移动操作，追求全身任务；**本赛题的正确形态是「站定 + 腰辅助 + 手臂主操作」**：把下肢当约束观测，把腰当零空间资源，把底盘当例外动作。这与「堆一个全身 MPC」相反，是**最小充分全身控制**。
- **技术可行性**：17-DoF QP 极小；URDF 可得时用解析 Jacobian/FK；缺失时用数据驱动 Jacobian（从公开数据拟合）或退化为 arm-only + 软限位；腰/臂权重可在线调（喂 IP-48）。
- **所需资源**：数据=公开数据集（姿态先验、腰使用统计）；算力=QP <1ms；仿真=MuJoCo（IP-35，条件）；接口=`lower_body` 观测 + pivot 动作 + joint/ee 通道。
- **落地步骤**：① 从数据提取 `(q_arm,q_waist,T_EE,q_stance)` 与腰使用先验；② 建 FK/Jacobian（URDF 或数据驱动）；③ 实现层级 QP；④ 平衡/支撑约束；⑤ 接入 IP-52 合同；⑥ E74 验收。
- **风险**：URDF 缺失（A17）→ 数据驱动 Jacobian / arm-only；腰权限小（E3）→ 只在余量不足时准入；平衡模型失真 → 保守支撑多边形 + `lower_body` 反馈；QP 不可行 → 放松到 EE-only 并上报；底盘例外动作引发大范围重定位 → 预算硬约束 + E77 证伪即默认固定。

**符号表**：

| 符号 | 含义 | 取值/来源 |
|---|---|---|
| `q` | 可控关节 `(q_arm^L,q_arm^R,q_waist)` | R^17 |
| `q_stance` | 下肢平衡姿态 | `lower_body[0:12]` 观测 |
| `p` | pivot 常规子空间 `(vx,vy,wz,height)` | 默认 `vx=vy=wz=0`（E2） |
| `T_i(q)` | EE 位姿 | `FK_i(q_arm^i,q_waist)` |
| `J_i,J_rel` | EE / 双臂相对位姿 Jacobian | URDF 或数据驱动 |
| `S` | 支撑多边形 | 足底/`lower_body` + 保守外扩 |
| `W` | 关节权重（含力矩/热） | IP-48 热账联动 |
| `w(q)` | 可操作度 | `sqrt(det(JJᵀ))` |
| `μ_min,d_min` | 腰准入阈值 | E74 标定 |

**算法（层级 QP）**：
```
输入：位姿合同 C_L,C_R（IP-52）、q、q_stance、ledger(热/步数)
0. 默认 p=p0；仅当 feasible=0 且预算允许时启用例外重定位
1. 计算 Δξ_i^des = log(T_i^des ⊖ b_i ⊖ T_i(q))，Δξ_rel^des
2. 层级求解：
   H0: J_i q̇ = Δξ_i^des (EE 主任务，软约束 δ_i)
   H1: J_rel q̇ = Δξ_rel^des (双臂相对，软约束)
   H2: CoM/ZMP(q,q_stance) ∈ S (硬约束)
   H3: q∈[q_min,q_max], q̇∈[q̇_min,q̇_max], d_self≥ε, w(q)≥w_min (硬)
   H4: 姿态正则 (腰回先验、关节远离限位) (零空间)
3. 腰准入：若 μ<μ_min 或 d_lim<d_min 或 双臂相对误差>ε_rel：
      放开腰的 H4 权重（允许腰参与）；否则腰锁在姿态先验附近
4. 热感知：W ← W0 + λ_H·diag(τ̂²)（IP-48 热态时抬高手臂/腰权重）
5. 输出 q̇* → 积分/限幅 → 关节命令；p 保持不变或例外重定位
6. 若 QP 不可行：逐级放松 H1→H0，记录降级并上报 IP-24
```
**复杂度**：变量 ≤20 维、约束 ≤60，QP <1ms（OSQP/qpOASES 级）；每步或每 chunk 调用均可。

**正确性论证**：
- **P65（层级不劣化）**：lexicographic QP 在可行时保证高优先级任务的残差 ≤ 低优先级任务；EE 是最高优先级，因此腰/平衡/姿态项不会以牺牲 EE 跟踪为代价换取自身目标（除非硬约束导致不可行，此时明确降级并上报）。
- **P66（腰准入的最小充分性）**：腰只在 `μ<μ_min ∨ d_lim<d_min ∨ 双臂相对误差>ε_rel` 时放开；否则腰锁在姿态先验，T-WBC 退化为 arm-only + 平衡约束，故腰不会在非必要情形下增加运动/热/步数（与 E7 一致）。
- **P67（平衡的保守充分条件）**：若 `CoM(q,q_stance)` 与 `ZMP` 均在保守外扩的支撑多边形 `S` 内，则站立平衡在模型误差范围内可维持；若模型误差超出外扩量，E74 用实测修正 `S`。
- **P68（热-力矩单调性）**：`W` 含 `τ̂²` 权重时，最小范数解降低 `Στ̂²`，与 IP-48 的 `Ĥ=∫τ̂²dt` 同向（继承 v17 P43）。

### 3.5 训练/服务伪代码（v18 增量版）

```python
# ===== 离线：位姿偏移辨识（IP-52，依赖公开数据，无需真机）=====
def identify_pose_bias(datasets):
    # datasets: 32 个 G1_Dex1_*（v1/v3 schema-aware）
    for task, ds in datasets.items():
        for side in ("left", "right"):
            r = ds.action[f"{side}_ee"](t) - ds.obs[f"{side}_ee"](t + 1)   # se(3)
            b0[task, side] = robust_mean(r)                  # 常量偏移（E4）
            Jb[task, side] = fit_config_dependent(r, ds.q)   # b(q) 残差项
            lag[task, side] = argmin_k ||action(t) - obs(t+k)||  # E4: 2–3 帧
    return b0, Jb, lag

# ===== 离线：腰使用先验 + 可操作度参考（IP-51）=====
def build_wbc_prior(datasets):
    q_prior = fit_waist_posture(datasets)        # 腰回先验（E3）
    w_ref = percentile(manipulability(datasets), 50)
    S = conservative_support_polygon(datasets)   # 支撑多边形（E3/URDF 或数据）
    return q_prior, w_ref, S

# ===== 运行期：主循环（IP-49/50/51/52）=====
def act_v18(obs, state, ledger):
    # 1. Δ-Plane：热/时延/步数（继承 v17）
    knobs = governor(ledger)

    # 2. Π-Plane：位姿合同（IP-52）
    assert state.plan is not None and all(has_cert(c) for c in state.plan.poses)
    C = [calibrate_and_check(T, obs, state.schema, state.task) for T in state.plan.poses]

    # 3. 规划/中层（仅当计划失效或可行性失败）
    if state.need_plan or any(not c.feasible for c in C):
        state.plan = step_efficient_planner(obs.language, state.semantic_map,
                                            p_s, W, M_f, scenario=state.sigma,
                                            feasibility=C, budget=knobs)
        state.need_refine = True

    # 4. TO（在合同目标上精修；deadline 硬截断）
    if state.need_refine:
        warm = stream_policy_head(state.plan.skill, obs)          # IP-43
        refined = hybrid_to(state.plan.waypoints, warm,
                            contracts=C, f_track=state.f_track,
                            envelopes=state.semantic_map.objects,
                            weights=(w_E, knobs.hot, w_P))
        state.traj = refined if refined is not None else warm      # 超时→VLA 伺服

    # 5. T-WBC（IP-51）：合同位姿 → 关节/腰命令
    q_cmd, p_cmd = torso_wbc(state.traj.next_pose(), obs.q, obs.lower_body,
                             contracts=C, support=state.S, W=thermal_weights(ledger))
    if q_cmd is None:                                             # QP 不可行
        q_cmd, p_cmd = arm_only_servo(state.traj.next_pose(), obs.q)
        failure_monitor.log("wbc_infeasible")

    # 6. 停稳协议（精密事件前）
    if state.plan.phase in PRECISION_PHASES:
        if not settle_ok(obs, C, state):
            return hold_command(state)                            # 计入 c_settle

    # 7. CBF 兜底 + 失败监测
    if not guard.cbf_check(q_cmd, p_cmd, obs, state.S):           # IP-33
        q_cmd, p_cmd = resample_or_fallback(state)
    r = pose_residual(obs, state.last_cmd)                        # Π-Plane 监视
    if residual_anomaly(r, C):
        M_f.log(obj=obs.focus, skill=state.plan.skill, sig="pose_residual")
        state.need_plan = True
    return adapt(q_cmd, p_cmd, control_space=state.control_space)
```

## 6. 清单迭代规则（继承 27–51 + 本轮新增 52–55）

- 继承规则 27–51（通道诚实/映射验证/SLO/fail-safe/灵感-现实校验/单模型合规/步骤分双解释/稠密监督/方法论遗产/元数据重照亮/语言口径分离/摊销/验证器分级/灵感词落地/层级联合规划/跨本体运动/流式韵律/渐进蒸馏/服务化/证书化/组合代数/热预算/期望得分/学习-TO/修剪优先）。
- **52（新增）：位姿合同一等原则**——任何进入执行的 EE 目标必须携带 `(T^des, ε, Σ, b, μ, feasible, settle, fallback)`；未校准的解析 EE 目标不得下发；位姿残差必须分离「常量偏移」与「速度相关滞后」。
- **53（新增）：全身控制最小充分原则**——只使用**实测活动量与边际收益**都足够的自由度；底盘默认固定、腰按余量准入、下肢只作约束观测；不允许「为了全身而全身」。
- **54（新增）：规划-执行-验收分离原则**——位姿里规划（语义/容差/可行性）、关节里执行（更好跟踪，E5）、位姿里验收（残差/合同），三者共享同一份 `C`。
- **55（强化 51）：修剪优先**——每轮至少将 ≥2 项「能力展示型而非得分型」设计降级 P2 并登记理由；P0 核心 IP ≤6；新增必伴随对应旧项修剪或合并。

**本轮最大风险一句话**：全身自由度可能小到「腰只是 5–10° 微调」，而 1 厘米级 EE 偏移可能只是公开数据集 v3.0 的记录约定（旧 schema 仅 -1~-4mm）、未必等于评测端真实约定——「躯干辅助 + 位姿合同」随时可能退化为两个只在离线数据上成立的机制；以 E73–E78 六重守门，按「位姿校准 > 腰辅助 > 底盘例外」优先序保底，全败即回退 v17。

**当前最值得押注**：**IP-52 POSE-CONTRACT（末端位姿合同）**——它是本轮唯一**可以在不碰真机、只用公开数据就先证实/证伪**的核心线：E4 已给出 1 厘米级稳定偏移，P61 预测校准可把准静态位姿误差降 35–45%，E73/E75 两个离线实验即可判定；它同时是 IP-49（可行性折价）、IP-50（TO 目标校准）、IP-51（位姿→关节的桥）、IP-24（残差失败签名）的共同接口。IP-51 是它的执行侧放大器，但若只能保留一条新线，保留 IP-52。
