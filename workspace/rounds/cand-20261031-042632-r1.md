# 第 13 轮 / 新循环 R1 · TOOL-DEADLINE：让同一个 VLA 学会「调用工具」，让服务层学会「按 deadline 出 chunk」，用产学研联盟补齐五类泛化

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新灵感循环第 1 轮，三个词是「**产学研合作**」「**工具调用**」「**实时推理**」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是把它们收束成一个更硬的系统命题：**单模型不是只能输出动作；它可以在同一个 checkpoint 里输出「工具调用 + 动作 chunk」，由确定性工具补齐几何、校准、恢复；服务层则按每个端口的 deadline 选择 chunk 长度和调度策略；数据缺口用产学研五轴数据联盟补，而不是继续堆一个更大的模型。**

## 0. 先给结论：瓶颈已经从「模型会不会」变成「工具来不来得及」

截至 2026-10-31，官网首页、榜单页、运行页均返回约 7 KB 的占位页，`leaderboard_data.json` 返回 HTML，搜索索引快照显示排行榜仍是 **Coming Soon**。因此上一轮记录的 MolmoAct2 29.7%、WALL-OSS 28.5% 等数字**今天无法复核**，本轮只把它们当作历史快照（C 级设计假设），不再据此推导“谁领先”。

可复核的事实反而更清楚：

1. **规则堵死了“再加一个学习模型”的捷径**：所有任务必须基于同一模型，不得混合多个模型测试；但确定性工具、控制器、离线 teacher 不在“第二个学习模型”之列。
2. **API 堵死了“高频闭环”的幻想**：四路 RGB、无深度/力/触觉；`action_chunk_size` 固定；chunk 内没有新观测、没有打断机制；`meta.token` 每次都要带。
3. **官方 WLA 堵死了“从零训大模型”的性价比**：6B、约 2500 h 真机、64 任务、54 维动作/60 维状态、`chunk_size=30` @30 fps，冻结 VLM 只训 action head + state projector，单张 24 GB GPU 可微调；server 是 **stateless、同步、单请求、无 batching/async**。
4. **数据堵死了“只靠现有 33k 演示”的泛化**：33,276 eps / 18,282,246 frames / 169.28 h，但五类泛化轴（位置、干扰物、背景、未见物品、人为干扰）在现有数据里覆盖不均；官方任务字符串里还藏着 **5 个 `@` 分隔的复述**，训练时若整串输入就是分布错误。
5. **外部基准给出校准**：ManipArena（arXiv 2603.28545）上最佳 specialist 951/1500（63.4%），WALL-OSS-0.5 多任务 865/1500（57.7%），π0.5 626→703（41.7%→46.9%）；语言粒度 L2 最利于执行、L3 最利于语义；balanced 200/task 可优于约 500/task。说明“数据配比 + 语言粒度”比“再大一圈”更可能涨点。

所以本轮的押注是 **TOOL-DEADLINE**：

> **同一个 VLA checkpoint 在输出动作 chunk 的同时，输出结构化工具调用（工具名、参数、置信度、deadline）；工具库全部是无学习权重的确定性 CV/几何/IK/伺服/碰撞/恢复/检索/标定原语；离线 VLM/LLM 只做 teacher 生成标签，测试时绝不加载第二个学习模型。服务层按端口 deadline 自适应选择执行 horizon，用 RTC/FASTER/Armory 类方法把“反应时间”压到 200–300 ms，同时用多副本/排队控制保证 N 台机器人并发时不超时。数据侧用产学研联盟按五类泛化轴建覆盖矩阵和机构级 holdout。**

三个可验证创新点：

1. **TC-VLA**：单模型输出工具调用；工具无学习权重；teacher 仅离线；用 G0/G1 验证“工具调用是否真的比纯动作 chunk 更准、且不违反单模型”。
2. **DAMS**：deadline-aware multi-tenant serving；按 `T_react = RTT + queue + infer + (H_exec-1)/f` 反解 `H_exec`；用 RTC/FASTER/Armory/AutoHorizon 做 chunk 融合、采样和跨机器人调度；用 G2/G3 验证 p99 与成功率拐点。
3. **GDC + LLBC + FASS**：产学研五轴数据联盟、语言阶梯 + 平衡课程、失败图谱 + 步骤分整形；用 G4/G5/G6 验证泛化缺口、语言鲁棒性和步骤分。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **工具调用** | VLA 同一 checkpoint 输出 `tool_call`；工具库为确定性 CV/几何/IK/伺服/碰撞/恢复/检索/标定；离线 teacher 只生成标签 | 不在测试时调用第二个 VLM/LLM；不用 SAM2/GroundingDINO/CLIP 等学习型感知工具；不做“VLM 规划 + VLA 执行”的双模型 |
| **实时推理** | 每端口 deadline 传播；自适应 `H_exec`；RTC 重叠区修补；FASTER horizon-aware 采样；Armory 多机器人调度；多副本/排队控制 | 不假设一张 GPU 能同时给 N 台机器人做 10 Hz 的 6B 推理；不做 30 Hz 广域网闭环 |
| **产学研合作** | GDC 五轴覆盖矩阵、机构级 holdout、统一 LeRobot schema、数据卡/许可/隐私、算力与机时交换、联合 benchmark/论文 | 不把“合作”写成口号；不做无 holdout 的数据堆砌；不泄露测试场景 |

## 1. 本轮新核实的事实（只列会改变方案的）

### 1.1 规则：单模型、32 任务、10 次/任务、5 类泛化各 2 次、单任务不计分通道

官方参赛手册（飞书，2026-10-31 复核）明确：

- 所有任务须基于**同一模型**完成，不得混合多个模型一起测试；模型类型不限。
- 32 个任务，每个任务 10 次独立运行；5 类泛化各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
- 单次真机执行上限 **180 s**；排名先看 32 任务总平均成功率，成功率相同看总平均步骤分，再相同看更早提交。
- 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态必须隔离。
- 另有**不计分的单任务测试通道**，可用于单任务成功率/步骤分验证。

**对方案的约束**：TC-VLA 的工具必须是“确定性原语”，不能是第二个学习模型；DAMS 必须按 N 端口并发设计；单任务通道是唯一敢做 A/B 的地方。

### 1.2 API：四路 RGB、无深度/力/触觉，`action_chunk_size` 决定反馈周期

提交模板（`unitreerobotics/unibot_submission` README v2，2026-10-31 复核）给出：

- 观测：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB 480×640；双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str`。
- 动作：`joint` 或 `ee` 互斥；`action_chunk_size` 固定；`meta.token` 每次 `get_action` 都要带。
- `obs_delta_indices` 决定传哪些键、堆叠几帧；`image_resize` 可缩放。**没有 depth、camera_info、force/torque、tactile。**
- README 明确：`action_chunk_size` 是每次 `get_action` 返回的 leading time-axis 长度；index 0 先执行，其余按顺序执行，直到 evaluator 再次调用 `get_action`。**chunk 内没有新的观测，也没有打断机制。**
- 评测端逐调用记录延迟、波动和动作统计规律，作为结果可信度的一部分。

**关键推论**：如果 `H_exec=30`、30 Hz，一次调用后有 1 s 开环；如果 `H_exec=3`，反馈周期 100 ms，但每端口调用率从 1 Hz 升到 10 Hz。N=4 时总调用率 40 Hz，6B 模型单卡 100 ms/次只能承 10 Hz——**反应时间与吞吐是耦合的，不能只把 chunk 调小。**

- **UnifoLM-WLA-1.0**：6B 参数，约 2,500 小时真机数据，64 个任务，支持二指夹爪和五指灵巧手；2026-09-28 开源 Base 权重、微调代码、模型服务器。

## 2. 诊断：三个“来不及”

### 2.1 工具来不及：模型只能输出动作，不能“承认自己需要一个工具”

接触密集任务（插入、挂杯、拉拉链、拧瓶盖、开锁）最后 3 cm 需要的是几何闭环，而不是更大的语义模型。纯 VLA 只能输出下一个 chunk；它没有“调用一次 PnP/IBVS/IK 检查”的接口。结果是要么用 30 步开环硬扛，要么在模型外面再挂一个学习模块——后者违反单模型。

**TC-VLA 的切口**：让同一个 checkpoint 在动作头旁边输出一个离散工具 token + 连续参数；工具是无学习权重的确定性原语。模型仍然只有一个，工具不是模型。

### 2.2 推理来不及：N 台机器人 × 短 chunk = 吞吐爆炸

反应时间近似：

```text
T_react = τ_up + W_q + T_infer + τ_down + (H_exec - 1) / f
```

- 若 `T_infer=100 ms`、RTT 往返 60 ms、排队 20 ms、`H_exec=30`、f=30 Hz：`T_react≈1.15 s`。
- 若 `H_exec=3`：`T_react≈247 ms`，但每端口调用率 10 Hz；N=4 时 40 Hz，单卡 6B 承不住。
- 若 `H_exec=8`：`T_react≈413 ms`，每端口 3.75 Hz；N=4 时 15 Hz，单卡 10 Hz 仍不够，需 2 副本（ρ=0.75）。
- 所以“固定 chunk”不是最优；**每个端口、每个任务阶段、每个 N 都应有不同的 `H_exec`**。这就是 DAMS。

### 2.3 数据来不及：五类泛化不是架构问题，是覆盖问题

现有 33k 演示主要覆盖“正常位置 + 正常背景 + 正常物体 + 无人类干扰”。五类泛化各占 20% trials，但训练集里的对应分布远不足。继续调大模型不解决“没见过这个背景/这个物体/人突然把杯子挪走”。需要的是**按轴采集、按机构 holdout、按覆盖矩阵分配采集预算**——这正是产学研联盟能做的事。

## 3. 方法：TOOL-DEADLINE

### 3.1 总架构

```text
┌────────────────────────────────────────────────────────────┐
│ Evaluator (N ports 8765..8765+N-1)                          │
└───────────────┬────────────────────────────────────────────┘
                │ websocket: obs / action chunk / token
                ▼
┌────────────────────────────────────────────────────────────┐
│ Per-port Gateway (CPU)                                      │
│  ├─ deadline estimator (RTT, queue, control period)         │
│  ├─ language normalizer (5 paraphrases → canonical)         │
│  ├─ plan cache + RTC overlap buffer                         │
│  ├─ tool runtime (CV/geometry/IK/servo/collision/recovery)  │
│  └─ action adapter (WLA 54D → contest 21D)                  │
└───────────────┬────────────────────────────────────────────┘
                │ async request with deadline + priority
                ▼
┌────────────────────────────────────────────────────────────┐
│ Shared Serving Layer (GPU pool, same checkpoint replicas)   │
│  ├─ Armory-style per-port scheduler                         │
│  ├─ FASTER-style horizon-aware sampling                     │
│  ├─ RTC-style chunk inpainting                              │
│  └─ admission control / timeout fallback                    │
└────────────────────────────────────────────────────────────┘
```

- **唯一学习模型**：VLA（官方 WLA 微调 action head + tool head）；多副本是同一 checkpoint，不是多个模型。
- **确定性工具**：无学习权重；CPU 执行；可解释、可限幅、可关闭。
- **数据资产**：33k 演示 → 工具标签/关键帧/失败图谱；GDC 补五轴。
- **数字孪生**：只做工具验证、延迟/增益标定，不训练策略。

### 3.2 TC-VLA：把工具调用放进同一个 checkpoint

动作头输出两组量：

```text
a_chunk[0:H_plan, D_action]      # 与原 WLA 相同
tool_token ∈ {none, depth, segment, match, pnp, ibvs, ik, grasp, collide, recover, retrieve, calibrate}
tool_args ∈ R^k                  # 目标点/位姿/ROI/增益/重试次数等
tool_conf ∈ [0,1]
tool_deadline_ms ∈ R+
```

执行规则：

```text
if tool_conf < θ_tool or tool == none:
    execute a_chunk[0:H_exec]                       # 纯 VLA 回退
else:
    out = tool(obs, a_chunk, tool_args)             # 确定性工具
    a_cmd = compose(a_chunk, out)                   # 修正/投影/重试/恢复
    execute a_cmd[0:H_exec]
```

工具不是“另一个策略”，它只做四类事：

1. **几何修正**：PnP/IBVS/PBVS 把动作投影到目标相对位姿；
2. **可行性投影**：IK/关节限位/碰撞检查把动作裁到安全域；
3. **状态估计**：双目深度/颜色分割/模板匹配/ORB 给出目标位姿或置信度；
4. **恢复原语**：撤回、重抓、重新接近、重新观测、请求重规划。

**合规关键**：工具代码里不允许出现可学习权重；不允许在测试时加载 SAM2/GroundingDINO/CLIP/第二个 VLA；离线 teacher（VLM/LLM）只生成训练标签，不进入部署镜像。若使用 VLA 自身特征做检索/匹配，属于同一 checkpoint（C3 模式），允许。

### 3.3 工具标签怎么来：离线 teacher + 执行验证

```text
1. 用状态/动作变化 + 离线 VLM 把每条成功演示切成阶段（approach/grasp/transport/insert/release/recover）。
2. 对每个阶段，从工具语法里枚举候选工具调用（如 pnp(target=cup_handle), ibvs(roi=hole), ik(limit=...)）。
3. 在回放/仿真里执行候选工具，保留“降低误差且不破坏成功”的调用；失败的调用作为负样本。
4. 用 (obs_t, phase, language) → (tool_token, args, conf, deadline) 训练 tool head；
   用动作流匹配训练 action head；两项联合，共享 VLA backbone。
5. 在 holdout 演示上验证：工具调用准确率、工具执行成功率、端到端成功率。
```

标签质量门：工具程序在回放中执行成功率 ≥85%，tool token 在 holdout 上 top-1 ≥90%，否则不进入真机。

### 3.4 DAMS：按 deadline 选 horizon，而不是拍一个常数

给定端口 deadline `D`（例如人扰恢复 250 ms、常规执行 400 ms），反解：

```text
H_exec* = clip( floor( f × (D - τ_up - W_q - T_infer - τ_down) ) + 1, 1, 30 )
```

若 `H_exec* < H_min`，触发降级：

1. **优先人扰端口**：提高优先级、抢占队列；
2. **RTC 修补**：新 plan 与旧 chunk 重叠区做 inpainting，避免跳变；
3. **FASTER 采样**：按剩余 horizon 调整 flow 采样步数，缩短推理；
4. **缓存/外推**：用旧 plan 的速度前馈 + 视觉伺服短闭环撑过一帧；
5. **多副本**：同一 checkpoint 多 GPU 副本，Armory 调度；若只有单卡，则按 N 自适应增大 `H_exec`，保证 ρ<1。

排队约束：

```text
λ = N × f / H_exec
ρ = λ × E[T_infer] / m < 0.8
```

例：N=4、H=8、f=30 → λ=15 Hz；E[T_infer]=100 ms、m=2 → ρ=0.75，可稳定。N=8、H=8 → λ=30 Hz，需 m=4 或 H=15。

**这是本轮最硬的工程结论**：短 chunk 不是免费的；它把 GPU 吞吐换成了反应时间。DAMS 要显式做这个交换。

### 3.5 GDC：产学研五轴数据联盟

把“合作”拆成可执行的四件事：

1. **覆盖矩阵**：32 任务 × 5 轴 = 160 格；每格记录 episodes、场景数、物体数、机构、许可、holdout 标记。
2. **统一 schema**：LeRobot v2.1 + `gdc/axis`、`gdc/scene_id`、`gdc/object_id`、`gdc/institution`、`gdc/split`；四路 RGB 480×640 @30 fps；语言保留 5 个复述。
3. **机构级 holdout**：每个伙伴留出一个场景/物体/背景，只用于跨机构评测；测试场景绝不进训练。
4. **算力/机时交换**：企业出 GPU 与机器人机时，高校出场景、操作员、人类干扰演员，研究院出 benchmark 与评测；按数据量/机时折算贡献，联合署名。

目标增量：在 33k 基础上补 **2,000–3,200 eps**，优先补 human / novel object / background 三轴；每格 ≥20 eps（重点任务）或 ≥10 eps（长尾）。这比再训一个 14B 便宜得多。

### 3.6 LLBC：语言阶梯 + 平衡课程

- 官方 `meta/tasks.parquet` 已有 5 个复述；用它们做 L0（任务名）/L1（短祈使）/L2（阶段/可供性）/L3（目标/语义）四档。
- 离线 LLM 生成 L2/L3，人工抽检；训练时按 70/20/10 采样 L0-L1/L2/L3，10% 语言 dropout。
- 平衡采样：每 epoch 每任务上限 200 eps，难任务（长时、接触密集、human 轴）在 epoch 2 后过采样 1.5×。
- 测试时只做确定性归一化（小写、去标点、同义词映射、复述切分），**不调用 LLM**；不把多个复述拼成一次输入。

### 3.7 FASS：失败图谱 + 步骤分整形

- 失败分类：感知（找不到/位姿错）、抓取（漏抓/滑移/抓错）、接触（卡住/过力/对不准）、顺序（步骤错/跳步）、恢复（重试失败/碰撞）、超时、其他。
- 用离线 VLM + 人工抽检给单任务通道的失败打标签，形成 `task × axis × failure` 图谱。
- 步骤分整形：从任务描述/演示推断 rubric 子目标；同一 checkpoint 加辅助 progress head 预测子目标完成；恢复策略优先“保留已完成步骤”，避免为了重试把已得分步骤推倒。
- 工程分配：`priority_t = q_t × Δ_t / cost_t`，其中 `q_t` 是目标失败模式占比，`Δ_t` 是预期增益，`cost_t` 是工程+机时；每 3–5 次单任务测试更新。

### 3.8 RGK / CRSC：两个高杠杆工具

- **RGK（Retrieval-Guided Keyframes）**：从 33k 成功演示检索 `T_target_ee*` 和腕部目标图；在线按任务/阶段/描述子 top-k，几何一致性重排；置信度低回退 VLA。解决“目标长什么样”而不是“目标在哪”。
- **CRSC（Cross-Robot Self-Calibration）**：利用头双目内参、腕部彩色内参、URDF、EE 位姿做手眼 AX=XB；每机器人/端口缓存外参和 TCP 偏移；用重投影误差监控，超阈值回退标称值。解决 N 台机器人装配差异。

### 3.9 WMDE（explore）：世界模型只做离线数据引擎

用 WMA/视频世界模型生成反事实视频，补 human/novel object/background 稀有轴；用物理合理性过滤；把生成的“工具调用成功/失败”标签蒸馏进 VLA。**测试时不加载世界模型**，只作为离线数据引擎。风险高、优先级低，不占关键路径。

## 4. 与第 10/11/12 轮的关系：保留、升级、剪枝

**保留**：

- FACT-VLA 的相位化 BC、CAC 柔顺执行、EGP 证据门控；
- GEO-RESIDUAL 的动作条件化残差、米制表面距离、编辑检测；
- CHUNK-SERVO 的演示检索相对目标、5 步伺服、数字孪生标定；
- 官方 WLA 基座、33k 演示、单任务通道。

**升级**：

- 控制器 → 工具接口：把 CHUNK-SERVO 的伺服/检索/标定封装成 VLA 可调用的确定性工具；
- 固定 chunk → deadline-aware horizon：从“扫 H_c”升级为“按端口 deadline 和 N 反解 H_exec”；
- 单机数据 → 产学研五轴联盟：从“自己采一点”升级为“覆盖矩阵 + 机构 holdout + 算力交换”；
- 语言整串 → 语言阶梯：利用 5 个复述做 L0-L3，而不是把整串喂进去；
- 成功率 → 成功率 + 步骤分：用失败图谱和 progress head 优化 tie-break。

**剪枝**：

- 不做逐任务 LoRA experts + merge（规则风险高、合并损失难控）；
- 不做量化作为主线（当前瓶颈是延迟/工具/数据，不是显存）；
- 不做完整数字孪生/世界模型训练（折叠进工具验证与 GDC）；
- 不做 TTA（收益低、延迟高）；
- 不从零训 6B/14B；
- 不做第二个学习模型/残差策略/独立视觉编码器（单模型风险）；
- 不做 6D 物体位姿网络（透明/变形不可靠；用 PnP/IBVS/检索）；
- 不做力/触觉闭环（API 没有）；
- 不做 30 Hz 广域网伺服（RTT 不允许）；
- 不把榜单任务排名当难度表（旧数字不可复核）。

## 5. 实验门 G0–G8

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | 工具标签是否可信？ | 回放工具执行成功率 ≥85%；holdout tool top-1 ≥90% | 缩工具集，只保留 pnp/ibvs/ik/recover |
| G1 | TC-VLA 是否合规且不降点？ | 部署只有一个 checkpoint；工具开销 ≤10 ms；端到端不低于纯 VLA | 关闭 tool head，回退纯 chunk |
| G2 | DAMS 能否守住 deadline？ | N=4/8 时 p99 ≤250/400 ms；deadline miss <1%；timeout 不升 | 增大 H_exec、加副本、降分辨率 |
| G3 | 短 chunk 是否真的涨点？ | H_exec ∈ {3,5,8,15,30} 中存在成功率拐点，且 p99 可接受 | 选保守 H，仅在人扰/接触段缩短 |
| G4 | 语言阶梯是否有效？ | 未见复述 +5pp；L2/L3 不劣于 L0 | 回退 5 复述随机采样 |
| G5 | GDC 是否补上泛化？ | 目标轴 gap 相对缩小 ≥30%；ID 不回归 >2pp | 缩到 human/background 两轴 |
| G6 | 步骤分是否提升？ | 同成功率下步骤分 +10%；恢复不丢已完成步骤 | 只保留失败图谱，不做整形 |

| G8 | 32×10 干跑是否稳定？ | N 端口隔离、reset 干净、内存不涨、无死锁 | 回退单端口/基线 |

所有门先在离线回放和单任务不计分通道上过；没有过门，不烧正式提交。

## 6. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定为第二个模型 | 工具无学习权重；teacher 仅离线；多副本同一 checkpoint；提交材料写清 C1/C2/C3 |
| 工具调用误触发 | 动作被错误修正 | 置信度门控；限幅/限速；失败回退纯 chunk；工具可一键关闭 |
| 短 chunk 吞吐爆炸 | N 端口超时 | DAMS 反解 H_exec；多副本；优先级；缓存外推 |
| RTT 抖动 | deadline 估计错 | 在线测 RTT 分位数；保守 deadline；超时回退旧 plan |
| 工具标签噪声 | 蒸馏学错 | 回放执行验证；负样本；人工抽检；G0 门 |
| 五轴数据不足 | 泛化门不过 | 先补 human/background；机构 holdout；数据卡 |
| 机构数据合规 | 不能合并/发布 | DUA、脱敏、许可、贡献折算；只共享权重/统计量也可 |
| 校准动作不被允许 | CRSC 无法在线执行 | 评测前离线标定；自然运动自标定；回退标称 |
| 步骤分 rubric 未知 | 整形方向错 | 用子目标代理；单任务通道验证；不声称精确 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |

## 7. 一句话押注

**把“再训一个模型”换成“让同一个 VLA 学会调用确定性工具”，把“固定 chunk”换成“按 deadline 选 horizon”，把“闭门造数据”换成“产学研五轴数据联盟”——在不违反单模型规则的前提下，同时压缩反应时间与泛化缺口。**

## 2. 创新点清单（持续迭代）

> 每条含：动机、与现有方案差异、技术可行性、所需资源、落地步骤、风险。状态：`主线` / `支线` / `观察`。

### I1. TC-VLA：单模型工具调用（主线）

- **动机**：纯 VLA 只能输出动作 chunk，接触段缺少几何闭环的“接口”；再加一个学习模块违反单模型。把工具调用放进同一个 checkpoint，可以在合规前提下获得闭环能力。
- **与现有方案差异**：MAESTRO 是“VLM coding agent + 工具库”，测试时两个模型；TC-VLA 是“同一 VLA 输出 tool token + action chunk”，测试时一个 checkpoint。与 CHUNK-SERVO 相比，工具不再由外层固定调度，而由模型按观测/阶段调用。
- **技术可行性**：动作头加一个离散分类头 + 参数回归头；工具库用 OpenCV/NumPy/SciPy/URDF/QP，无学习权重；离线 teacher 生成标签，回放执行验证。单张 24 GB GPU 可训。
- **所需资源**：官方 WLA 权重/微调代码；33k 演示回放；4 路相机数据；CPU 工具运行时；单任务通道。
- **落地步骤**：① 定义工具语法与 12 个原语；② 离线切阶段、枚举工具、回放验证；③ 联合训练 action head + tool head；④ 单任务 A/B（tool on/off）；⑤ 过 G0/G1 后进正式提交。
- **风险**：工具误触发、标签噪声、单模型解释争议；用置信度门控、限幅、回退纯 chunk、合规说明缓解。

### I2. DAMS：deadline-aware 多端口服务（主线）

- **动机**：N 台机器人并发时，短 chunk 把 GPU 吞吐变成瓶颈；固定 H_exec 无法同时满足反应时间与超时率。
- **与现有方案差异**：官方 server 是 stateless/同步/无 batching；DAMS 在其外做 deadline 传播、自适应 horizon、RTC 修补、FASTER 采样、Armory 调度、多副本/排队控制。
- **技术可行性**：网关层用 asyncio/消息队列；每端口维护 plan cache 和 RTT 统计；按公式反解 H_exec；RTC 用重叠区 inpainting 的简化版；FASTER 用减少 flow 步数的近似；多副本共享同一 checkpoint。
- **所需资源**：N 个端口模拟器/真机；GPU 池（至少 2 张 24 GB 卡做 N=4 压测）；网络 RTT 注入工具；延迟/成功率日志。
- **落地步骤**：① 建 N 端口回放压测台；② 测 RTT/推理时间分布；③ 实现 H_exec 反解与优先级；④ 扫 N×H_exec×副本数；⑤ 过 G2/G3/G8。
- **风险**：多副本被误判为多模型（需说明同一 checkpoint）；RTC/FASTER 近似实现效果打折；队列抖动导致 p99 超时。

### I3. GDC：产学研五轴数据联盟（主线）

- **动机**：五类泛化各占 20% trials，但现有 33k 演示覆盖不均；继续堆模型不解决分布缺口。
- **与现有方案差异**：不是“再采一点数据”，而是 32×5 覆盖矩阵、机构级 holdout、统一 LeRobot schema、数据卡/许可/隐私、算力/机时交换、联合 benchmark。
- **技术可行性**：LeRobot v2.1 已是官方数据格式；四路 RGB + 语言 + 本体状态可直接复用；每机构 200–400 eps 即可补 2,000–3,200 eps；holdout 按场景/物体/背景分组。
- **所需资源**：3–5 家伙伴（高校/企业/研究院）；G1 或同级机器人；操作员/人类干扰演员；GPU 机时；DUA/许可模板。
- **落地步骤**：① 定 schema 与数据卡；② 建覆盖矩阵与缺口清单；③ 各伙伴按轴采集；④ 机构 holdout 评测；⑤ 汇总训练/发 benchmark/联合署名。
- **风险**：数据合规、隐私、机构利益、采集质量不一致；用 DUA、脱敏、统一质检、贡献折算缓解。

### I4. LLBC：语言阶梯 + 平衡课程（支线，低成本高确定性）

- **动机**：官方任务字符串含 5 个复述；整串输入是分布错误。语言粒度影响执行与语义泛化。
- **与现有方案差异**：把 5 个复述拆成 L0–L3 阶梯，训练时随机采样 + dropout；平衡采样 + 难任务过采样。不是简单的“多语言增强”。
- **技术可行性**：离线 LLM 生成 L2/L3，人工抽检；训练代码只改数据加载；测试时确定性归一化，不调用 LLM。
- **所需资源**：任务文本、离线 LLM（一次性）、人工抽检 2 人日。
- **落地步骤**：① 解析 5 复述；② 生成 L2/L3；③ 改 sampler；④ 单任务 A/B；⑤ 过 G4。
- **风险**：生成文本偏离任务；用人工抽检和回退原始复述缓解。

### I5. FASS：失败图谱 + 步骤分整形（支线）

- **动机**：排名先看成功率，同分看步骤分；失败模式决定工程分配，但当前没有系统图谱。
- **与现有方案差异**：把单任务通道的失败按 task×axis×failure 分类；用子目标 progress head 做步骤分整形；恢复策略优先保留已完成步骤。
- **技术可行性**：离线 VLM + 人工抽检标注；progress head 与 action head 共享 backbone；不需要额外模型。
- **所需资源**：单任务通道 trial 日志；离线 VLM；标注人力。
- **落地步骤**：① 定 taxonomy；② 标 100–200 条失败；③ 训 progress head；④ 恢复策略 A/B；⑤ 过 G6。
- **风险**：rubric 未知、标注主观；用子目标代理、单任务验证、不声称精确。

### I6. RGK：检索引导的目标关键帧（支线，工具化）

- **动机**：接触段需要“目标长什么样/相对位姿”，纯动作回归难以稳定表达。
- **与现有方案差异**：从 33k 成功演示检索 `T_target_ee*` 和腕部目标图，作为 TC-VLA 的工具；不是第二个策略。
- **技术可行性**：离线关键帧抽取 + ORB/颜色直方图/VLA 特征索引；在线 top-k + 几何重排；CPU 可跑。
- **所需资源**：演示数据、特征索引、腕部目标图库。
- **落地步骤**：① 切阶段/抽关键帧；② 建索引；③ 接工具调用；④ 单任务 A/B；⑤ 过 G7。
- **风险**：透明/反光/变形/遮挡导致检索错；置信度低回退 VLA。

### I7. CRSC：跨机器人自标定（支线）

- **动机**：评测跨 N 台机器人，装配/相机外参/TCP 有差异；固定标定会漂。
- **与现有方案差异**：利用头双目内参、腕部彩色内参、URDF、EE 位姿做手眼 AX=XB；每端口缓存外参/TCP 偏移；重投影误差监控。
- **技术可行性**：经典手眼标定；10–20 个位姿；离线/评测前做一次；在线用自然运动细化。
- **所需资源**：标定板/标定物；每机器人 10–20 个位姿；端口缓存。
- **落地步骤**：① 离线标定流程；② 端口级缓存；③ 误差监控/回退；④ 跨机器人 A/B；⑤ 过 G7。
- **风险**：reset 不允许校准动作；用评测前标定/自然运动/标称回退。

### I8. WMDE：世界模型数据引擎（观察，不进关键路径）

- **动机**：human/novel object/background 稀有轴采集贵；世界模型可生成反事实数据。
- **与现有方案差异**：只做离线数据引擎/工具标签过滤器，测试时不加载世界模型；与“世界模型当策略”不同。

- **所需资源**：世界模型权重/推理算力；物理过滤器；人工抽检。

## 3. 问题形式化

### 3.1 单模型约束与工具合法性

设唯一学习模型为 `π_θ`，参数 θ 来自一个 checkpoint。允许的测试时计算：

```text
a, z = π_θ(obs, language)          # z = tool token + args + conf + deadline
a' = g(a, z, obs)                  # g 为确定性工具组合，无可学习参数
```

禁止：

```text
a' = g(a, π_φ(obs))                # φ 为第二个学习模型
a' = g(a, VLM_API(obs))            # 测试时调用外部 VLM/LLM
```

若工具使用 `π_θ` 内部特征（同一 checkpoint 的 encoder），属于同一模型，允许；若加载另一个预训练视觉模型，不允许。

### 3.2 延迟模型

```text
T_react = τ_up + W_q + T_infer + τ_down + (H_exec - 1) / f
```

- `τ_up/τ_down`：网络单程延迟；
- `W_q`：排队等待；
- `T_infer`：VLA 前向（含图像预处理/JPEG 解码）；
- `H_exec`：本次返回的 chunk 执行步数；
- `f`：控制频率（默认 30 Hz）。

端到端还包括 evaluator 执行 index 0 的时间；上式是“新观测到新动作开始执行”的近似。

### 3.3 deadline-aware horizon

给定端口 deadline `D`：

```text
H_exec* = clip( floor( f × (D - τ_up - W_q - T_infer - τ_down) ) + 1, 1, H_plan )
```

其中 `H_plan=30` 是 VLA 规划长度。若 `H_exec* < H_min`：

- 提高该端口优先级；
- 减少 FASTER 采样步数；
- 用旧 plan 外推 + 短伺服；
- 增加副本；
- 最后才降分辨率/缩图。

### 3.4 五轴覆盖矩阵

```text
C[t, a] = 任务 t 在泛化轴 a 上的有效 episodes 数
a ∈ {position, distractor, background, novel_object, human}
```

目标：

```text
C[t, a] ≥ 20   # 重点任务
C[t, a] ≥ 10   # 长尾任务
coverage = #{(t,a): C[t,a] ≥ threshold} / 160
```

机构 holdout：每个伙伴保留 `H_i` 个场景/物体/背景，训练集与 `H_i` 不相交；评测时按 `H_i` 分组报告。

### 3.5 步骤分与失败图谱

设 rubric 子目标为 `s_1..s_K`，步骤分为完成的子目标数/权重。失败图谱：

```text
F[t, a, m] = 任务 t、轴 a、失败模式 m 的次数
priority_t = q_t × Δ_t / cost_t
q_t = Σ_{m∈M_target} F[t, ·, m] / Σ_m F[t, ·, m]
```

`Δ_t` 是该任务可获得的成功率/步骤分增益估计，`cost_t` 是工程+机时成本。每 3–5 次单任务测试更新。

## 4. 系统设计

### 4.1 进程/端口拓扑

```text
Evaluator
  │  N ports (8765..8765+N-1)
  ▼
Gateway (per port, CPU)
  ├─ WS server
  ├─ obs preprocess / JPEG decode
  ├─ language normalizer
  ├─ deadline estimator (RTT EWMA + p99)
  ├─ plan cache (H_plan=30)
  ├─ RTC overlap buffer
  ├─ tool runtime (OpenCV/NumPy/SciPy/URDF/QP)
  └─ action adapter (54D → 21D)
  │
  ▼  async request (port_id, deadline, priority, obs, language)
Serving layer (GPU pool)
  ├─ scheduler (Armory-style)
  ├─ worker replicas (same checkpoint)
  ├─ FASTER-style sampling
  └─ response stream (action chunk + tool token)
```

- 每端口一个 Gateway 进程/协程，互不共享可变状态；`reset()` 清 episode 状态，不清标定缓存。
- Serving layer 只加载同一个 checkpoint 的多个副本；副本之间权重相同。
- 工具 runtime 在 CPU；GPU 只跑 VLA。

### 4.2 接口契约

```python
class PolicyService:
    def reset(self) -> None:
        # 清 episode 状态：plan cache、RTC buffer、工具状态、失败计数
        # 不清：CRSC 标定、语言归一化缓存、端口 RTT 统计

    def get_action(self, obs: dict, meta: dict) -> dict:
        # obs: 四路 RGB + joint/ee/gripper/lower_body + language
        # meta: token、deadline_ms、port_id、step_idx
        # return: action chunk (H_exec, D_action), action_type, meta.token
```

约束：

- `action_chunk_size` 在提交配置里固定；H_exec 是实际返回的 leading length，必须 ≤ 配置值。
- 每次响应都带 `meta.token`。
- chunk 内动作必须连续、限幅、满足关节/速度限制。
- 超时回退：返回缓存 plan 的前 H_exec 步，或安全保持动作。

### 4.3 `get_action` 伪代码

```python
def get_action(obs, meta):
    t0 = now()
    lang = normalize_language(obs["language"])        # 5 paraphrases → canonical
    port = meta["port_id"]
    deadline = meta.get("deadline_ms", default_deadline(port))

    # 1. 估 deadline / 选 horizon
    rtt = rtt_stats[port].p95()
    infer_est = infer_stats[port].p95()
    H = solve_horizon(deadline, rtt, infer_est, queue_est(port), f=30)

    # 2. 取/新鲜 plan
    plan = plan_cache[port]
    if plan is None or plan.age > max_plan_age or should_replan(obs, plan):
        req = make_request(obs, lang, H_plan=30, deadline=deadline, priority=priority(port))
        plan = serving_client.submit(req)             # async; may wait
        plan_cache[port] = plan
        rtc_buffer[port].update(plan)

    # 3. RTC 重叠区融合（若新 plan 与旧 chunk 重叠）
    a_chunk = rtc_buffer[port].blend(plan, obs)

    # 4. tool head 输出
    tool = plan.tool                               # token/args/conf/deadline
    if tool.conf >= THETA_TOOL and tool.deadline_ms >= elapsed_ms():
        out = run_tool(tool, obs, a_chunk, calib[port])
        a_chunk = compose(a_chunk, out)            # 修正/投影/恢复
    else:
        a_chunk = a_chunk                          # 纯 VLA 回退

    # 5. 安全投影
    a_chunk = clip_velocity(a_chunk, limits)
    a_chunk = collision_check(a_chunk, obs, calib[port])

    # 6. 返回 H_exec 步
    return {
        "action": a_chunk[:H],
        "action_type": "ee",
        "meta": {"token": meta["token"], "horizon": H, "tool": tool.name},
    }
```

### 4.5 动作适配（WLA 54D → 挑战赛 21D）

WLA 输出 54D：左右 EE 各 6、左右夹爪各 1、左右灵巧手各 6、腰 3、躯干 3、base 平移 2、base yaw 1、base pose 6、左右腿各 6。挑战赛 API 需要：

- `ee`：左右 EE 各 6（相对 xyz + rotvec）+ 左右夹爪各 1 + `lower_body[15]`；或
- `joint`：左右臂各 7 + 夹爪 1 + `lower_body[15]`。

适配规则：

1. 只取左右 EE 6D、夹爪 1D、`lower_body` 15D；
2. 丢弃灵巧手/base/腿（挑战赛桌面任务不需要）；
3. EE 动作从 WLA 的相对系转到 API 约定系；用 CRSC 校准 TCP；
4. `lower_body` 直接用观测值或零增量；
5. 输出前做速度/加速度限幅。

### 4.6 状态机

```text
IDLE → PLAN → EXECUTE → (TOOL) → EXECUTE → ...
                  │
                  ├─ tool_conf < θ → 纯 chunk
                  ├─ collision/limit → SAFE_HOLD → REPLAN
                  ├─ human_edit detected → HOLD → RELOCALIZE → REPLAN
                  ├─ failure classified → RECOVER → PLAN
                  └─ timeout → FALLBACK_CHUNK → PLAN
```

状态转换必须可中断；`reset()` 强制回 IDLE 并清 episode 状态。

## 5. TC-VLA：工具调用策略

### 5.1 架构

在官方 WLA 的 DiT action head 旁加两个轻量头：

```text
VLM encoder (frozen) ──► state projector ──► DiT action head ──► a_chunk[30, D]
                                   │
                                   ├──► tool token head (13 类)
                                   ├──► tool args head (K 维，按 token 选择)
                                   ├──► tool confidence head (1)
                                   └──► deadline head (1，回归剩余 ms)
```

- 共享 backbone；新增头参数量 <1%；
- 训练时 action loss + tool CE + args L1 + confidence BCE + deadline L1；
- 推理时一次前向同时出 action 和 tool；不增加第二次模型调用。

### 5.2 离线 teacher 与标签

```text
输入：33k 成功演示 + 任务文本 + 关键帧
1. 阶段切分：状态/动作变化 + 离线 VLM caption + 人工规则
2. 工具候选：按阶段从语法枚举（approach→pnp/pbvs；grasp→grasp.candidate；insert→ibvs/ik；fail→recover）
3. 回放验证：在仿真/回放中执行工具，保留“误差下降且不破坏成功”的调用
4. 负样本：执行后误差变大/碰撞/超时的调用
5. 标签：tool_token、args、conf（成功=1，失败=0）、deadline（阶段剩余时间）
```

质量门：

- 工具执行成功率 ≥85%；
- holdout tool top-1 ≥90%；
- 工具调用带来的端到端成功率不低于纯 VLA（G1）。

### 5.3 训练目标

```text
L = L_action + λ1 L_tool_CE + λ2 L_args + λ3 L_conf + λ4 L_deadline + λ5 L_progress
```

- `L_action`：流匹配/扩散损失（与 WLA 一致）；
- `L_tool_CE`：工具 token 分类；
- `L_args`：仅对有效 token 计算；
- `L_conf`：工具执行成功/失败 BCE；
- `L_deadline`：阶段剩余时间回归；
- `L_progress`：子目标完成辅助损失（FASS）。

训练策略：先冻结 VLM 训 action head 到基线，再加 tool head 联合微调；工具头学习率高于 action head；负样本按 1:2 过采样。

### 5.4 推理与回退

```text
if tool == none or conf < θ_tool:
    pure_chunk
elif tool == servo.* and target_conf > θ_geom:
    compose(action, servo_delta)
elif tool == ik/collide and infeasible:
    clip/stop + replan
elif tool == recover and retries < max:
    recover primitive
else:
    pure_chunk
```

θ_tool 在单任务通道扫 `{0.5, 0.7, 0.9}`；θ_geom 按重投影/特征置信度设。

### 5.5 合规模式

| 模式 | 做法 | 风险 |
|---|---|---|
| C1 离线标注 | teacher 只生成训练标签，部署镜像不含 teacher | 低 |
| C2 确定性工具 | 工具无学习权重，CPU 执行 | 低 |
| C3 同 checkpoint 特征 | 工具用 VLA encoder 特征做检索/匹配 | 低-中，需说明 |
| 禁止 | 测试时加载第二个 VLM/VLA/学习型检测器 | 高，不做 |

提交材料需写清：部署镜像的模型列表、工具列表、是否加载外部权重、teacher 是否仅在训练时使用。

## 6. DAMS：deadline-aware 多端口服务

### 6.1 延迟预算

以 N=4、f=30 Hz、`T_infer=100 ms`、RTT 往返 60 ms、`W_q=20 ms` 为例：

| H_exec | 每端口调用率 | 总调用率（N=4） | T_react（估） | 适用 |
|---:|---:|---:|---:|---|
| 30 | 1 Hz | 4 Hz | ~1147 ms | 安全基线/长程 |
| 15 | 2 Hz | 8 Hz | ~647 ms | 常规 |
| 8 | 3.75 Hz | 15 Hz | ~413 ms | 接触段 |
| 5 | 6 Hz | 24 Hz | ~313 ms | 精细接触 |
| 3 | 10 Hz | 40 Hz | ~247 ms | 人扰恢复（需多副本） |

单卡 6B 100 ms/次 → 10 Hz 上限；N=4、H=3 需要约 5 个等效副本（或更快 GPU），才能把 ρ 压到 0.8 以下。**短 chunk 不是免费的。**

### 6.2 自适应 horizon

```text
D = min(task_deadline, safety_deadline)
H = clip(floor(f × (D - rtt - queue - infer)) + 1, H_min, H_plan)
```

- 人扰/接触段：D=250 ms，H≈3–5；
- 常规搬运：D=400 ms，H≈8–12；
- 长程/低动态：D=800 ms，H≈20–30；
- 若 `H < H_min`，进入降级（优先级/FASTER/外推/多副本）。

### 6.3 RTC / FASTER / Armory

- **RTC**：新 plan 到达时，取旧 chunk 与新 plan 的重叠区，按时间权重做 inpainting/线性融合；避免 chunk 切换跳变。简化实现：重叠区用 `w(t)` 从旧到新平滑过渡，非重叠区用新 plan。
- **FASTER**：按剩余 deadline 调整 flow 采样步数（如 4→2→1）；优先保证 action 前几步质量；用 horizon-aware 噪声调度。
- **Armory**：按端口 deadline/优先级/剩余 chunk 做调度；短 deadline 优先；同优先级轮转；记录每端口 p99。
- **AutoHorizon**：按阶段动态 H；阶段分类可由 tool token/progress head 给出，避免额外模型。

### 6.4 排队与准入

```text
λ = N × f / H_exec
ρ = λ × E[T_infer] / m
```

- 目标 ρ ≤ 0.8；
- 若 ρ > 0.8：增大 H_exec 或加副本；
- 若仍 >1：拒绝低优先级请求，返回缓存 plan；
- 每端口令牌桶限流，防止单端口刷爆 GPU；
- 记录 deadline miss、timeout、p99、队列长度。

### 6.5 优先级与恢复

优先级：

```text
priority = base + w_human × I[human_edit] + w_contact × I[contact_phase] + w_deadline × urgency
```

- 人扰恢复最高；
- 接触段次之；
- 长程搬运最低；
- 低优先级可被抢占（返回缓存 plan）。

### 6.6 压测矩阵

| 维度 | 取值 |
|---|---|
| N | 1, 2, 4, 8 |
| H_exec | 3, 5, 8, 15, 30 |
| 副本数 | 1, 2, 4 |
| RTT | 0, 50, 100, 150 ms（注入） |
| 推理时间 | 50, 100, 200, 300 ms（模拟/实测） |
| 任务阶段 | 接近/抓取/搬运/插入/恢复 |

输出：成功率、步骤分、p50/p95/p99、deadline miss、timeout、GPU 利用率。

## 7. GDC：产学研五轴数据联盟

### 7.1 覆盖矩阵

```text
行：32 任务
列：position, distractor, background, novel_object, human
格：episodes 数、场景数、物体数、机构、许可、holdout 标记
```

优先级：

1. human（人为干扰）：现有数据最少，占 20% trials；
2. novel_object（未见物品）：外观/类别 OOD；
3. background（背景）：纹理/光照/桌面颜色；
4. distractor（干扰物）：遮挡/杂乱；
5. position（位置）：相对容易，可用现有数据 + 随机化补。

目标增量 2,000–3,200 eps；重点任务每格 ≥20，长尾 ≥10。

### 7.2 统一 schema

LeRobot v2.1 基础字段：

```text

observation.images.head_stereo_right  (480×640×3, 30 fps)
observation.images.wrist_left         (480×640×3, 30 fps)

meta/tasks.parquet
```

新增元数据：

```text
gdc/axis            ∈ {position, distractor, background, novel_object, human}
gdc/scene_id        (场景/桌面/光照)
gdc/object_id       (物体/受器类别与实例)
```

### 7.3 各轴采集协议

| 轴 | 采集要求 | 每任务目标 | 质检 |
|---|---|---:|---|
| position | 物体/受器位置随机化 5–10 cm、旋转 ±15°；覆盖工作空间 | 20–30 | 成功率 ≥80%，位姿覆盖均匀 |

### 7.4 机构级 holdout 与防泄漏

- 相邻帧/同一 episode 不跨 train/val；
- 测试 holdout 的场景/物体/背景绝不进入训练；
- 提交前做泄漏检查：图像哈希、场景 ID、物体 ID、文本模板。

- **DUA**：数据使用协议，限定用途、期限、销毁；
- **隐私**：人类演员需同意；不采集人脸/语音；视频中的人脸可模糊；

## 8. LLBC：语言阶梯 + 平衡课程

### 8.1 语言阶梯

| 层级 | 例子（以 HangCup 为例） | 用途 |
|---|---|---|
| L0 | `HangCup` / `hang the cup` | 规范名，评测常见 |
| L1 | `hang the cup on the rack` | 短祈使 |
| L2 | `grasp the cup by the handle and hang it on the hook` | 阶段/可供性，执行最稳 |
| L3 | `put the cup away where it belongs` | 目标/语义，泛化最好 |
| L4 | `hang the red cup, not the blue one` | 干扰/否定，压力测试 |

来源：官方 5 个复述 + 离线 LLM 生成 + 人工抽检。L0/L1 直接用复述；L2/L3 生成后抽检 10%。

### 8.2 训练课程

```text
epoch 0–1: 平衡采样，每任务 ≤200 eps/epoch；语言 70% L0-L1, 20% L2, 10% L3；dropout 10%
epoch 2+: 难任务（长时/接触密集/human）过采样 1.5×；L2/L3 比例提高到 30%；dropout 10%
```

平衡采样理由：ManipArena 的 balanced 200/task 可优于 ~500/task；避免长时任务支配梯度。

### 8.3 测试时归一化

```text
lowercase → strip punctuation → split '@' → take first non-empty → synonym map → canonical task name
```

不调用 LLM；不拼接多个复述；不把 L2/L3 注入测试输入（除非评测语言本身如此）。

### 8.4 预期与验证

- 未见复述 +5pp（C 级假设）；
- L2/L3 不劣于 L0；
- 语言 dropout 提升鲁棒性；
- 通过 G4。

## 9. FASS：失败图谱 + 步骤分整形

### 9.1 失败分类

| 模式 | 子类 | 例子 |
|---|---|---|
| perception | object_not_found, pose_error, occlusion | 杯子不在视野/位姿偏 |
| grasp | miss, slip, wrong_part | 没夹住/滑落/夹杯口 |
| contact | jam, over_force, misalign | 插不进/卡住/对不准 |
| sequence | wrong_order, skipped_step | 先放后抓/漏步 |
| recovery | retry_fail, collision | 重试失败/撤回撞 |
| timeout | slow, loop | 超 180 s/循环 |
| other | — | 未分类 |

### 9.2 标注管线

```text
单任务通道 trial → 离线 VLM caption + 状态/动作日志 → 规则分类 → 人工抽检 20%
→ F[t, a, m] 计数 → 失败图谱/热力图
```

### 9.3 步骤分整形

- 从任务描述/演示推断 rubric 子目标 `s_1..s_K`；
- progress head 预测 `P(s_k done | obs)`；
- 动作选择偏好“完成下一个未完成子目标”，而非重复已完成步骤；
- 恢复策略优先保留已完成步骤：撤回只到最近安全点，不重置整个任务；
- 若 rubric 未知，用子目标完成数作代理，不声称精确步骤分。

### 9.4 工程分配

```text
priority_t = q_t × Δ_t / cost_t
```

- `q_t`：目标失败模式占比；
- `Δ_t`：预期成功率/步骤分增益；
- `cost_t`：工程+机时；
- 每 3–5 次单任务测试更新；
- 先投 human/contact 高杠杆任务。

### 9.5 指标

成功率、步骤分、time-to-success、恢复率、误恢复率、失败模式分布。

## 10. RGK 与 CRSC

### 10.1 RGK 检索

离线：

```text
对每个任务/阶段/物体：
  取关键帧 k（接触前/抓取/插入/释放）
  T_target_ee*(k) = T_base_target(k)^-1 · T_base_ee(k)
  存 wrist 目标图、ORB/颜色直方图/VLA 特征、物体/受器位姿
```

在线：

```text
query = (task, phase, object_category, current_wrist_feature)
top-k = ANN/暴力检索 → 几何一致性重排 → 输出 (T_target_ee*, wrist_goal, conf)
```

置信度低回退 VLA；透明/反光/变形任务只启用 2D 模板匹配或禁用。

### 10.2 CRSC 标定

```text
输入：头双目内参、腕部彩色内参、URDF、EE 位姿、腕部图像
方法：AX=XB 手眼标定；10–20 个位姿；重投影误差优化
输出：T_ee_cam、TCP 偏移、每端口缓存
监控：重投影误差 >5 px → 回退标称/重新标定
```

评测跨 N 台机器人时，按端口/机器人指纹加载标定；`reset()` 不清标定。

### 10.3 与 TC-VLA 的集成

- `calibrate.handeye` 在 episode 开始/空闲时调用（若允许）；
- `retrieve.keyframe` 在接近/接触阶段调用；
- 工具输出作为动作修正/目标，不替代 VLA 的语义规划；
- 工具失败不影响主 chunk 执行（回退）。

| 语言 L0 vs L2 vs L3 | 语言粒度 |
| 平衡 vs 非平衡 | 数据配比 |
| GDC 轴数据 on/off | 泛化 gap |
| RGK/CRSC on/off | 工具贡献 |

### 11.6 门 G0–G8

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | 工具标签可信？ | 回放执行成功率 ≥85%；holdout top-1 ≥90% | 缩工具集 |
| G1 | TC-VLA 合规且不降点？ | 单 checkpoint；工具开销 ≤10 ms；不低于纯 VLA | 关 tool head |
| G2 | DAMS 守 deadline？ | N=4/8 p99 ≤250/400 ms；miss <1% | 增 H/副本 |
| G3 | 短 chunk 涨点？ | H∈{3,5,8,15,30} 有拐点且 p99 可接受 | 保守 H |
| G4 | 语言阶梯有效？ | 未见复述 +5pp；L2/L3 不劣于 L0 | 回退 5 复述 |
| G5 | GDC 补泛化？ | 轴 gap 相对缩小 ≥30%；ID 不回归 >2pp | 缩两轴 |
| G6 | 步骤分提升？ | 同成功率 +10%；恢复不丢步骤 | 只留图谱 |
| G7 | RGK/CRSC 可用？ | top-5 ≥80%；重投影 ≤5px；方差下降 | 关工具 |
| G8 | 32×10 稳定？ | 端口隔离、reset 干净、无死锁 | 回退基线 |

## 13. 风险与合规

### 13.1 单模型合规

| 模式 | 描述 | 允许 |
|---|---|---|
| C1 | 离线 teacher 只生成标签，部署不含 teacher | 是 |
| C2 | 确定性工具/控制器，无学习权重 | 是 |
| C3 | 工具使用同一 checkpoint 的内部特征 | 是（需说明） |
| C4 | 多副本同一 checkpoint | 是（需说明） |
| X1 | 测试时加载第二个 VLM/VLA/检测器 | 否 |
| X2 | 测试时调用外部 LLM API | 否 |
| X3 | 逐任务学习策略/残差网络 | 否 |

提交材料：模型清单、checkpoint 哈希、工具清单、依赖库、是否联网、teacher 使用说明。

### 13.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 工具误触发 | 动作被错误修正 | 置信度门控、限幅、回退纯 chunk、可关闭 |
| 工具标签噪声 | 蒸馏学错 | 回放验证、负样本、人工抽检、G0 |
| 短 chunk 吞吐爆炸 | N 端口超时 | DAMS 反解 H、多副本、优先级、缓存 |
| RTT 抖动 | deadline 估计错 | 在线 p95/p99、保守 deadline、超时回退 |
| 多副本被误判 | 合规争议 | 同一 checkpoint、文档说明 |
| GDC 数据合规 | 不能合并/发布 | DUA、脱敏、许可、贡献折算 |
| 机构 holdout 泄漏 | 指标虚高 | 场景/物体/背景分组、哈希检查 |
| 校准动作不允许 | CRSC 失效 | 评测前离线标定、自然运动、标称回退 |
| 步骤分 rubric 未知 | 整形方向错 | 子目标代理、单任务验证、不声称精确 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；SE≈2.4pp |
| 榜单旧数字误导 | 方向错 | 不把旧榜单当 SOTA/难度表 |
