# 第 2 轮（UniBot 线 · 第 2 轮；本轮灵感：「轨迹优化」×「模块化设计」）

> **承接声明**：第 1 轮已把基线从 MetricVoiceGauge 重新基线化到 UniBot-V1（Unitree G1、32 桌面任务、5 类泛化场景、单通才模型、远程 API），并建立三层栈 + 工程层、IP-01…IP-08、定义 U1–U12、引理 L1–L7、实验 E601–E618。本轮**不推倒重来**：保留上述编号，新增 U13–U18、L8–L11、E619–E630。
> **情报纪律**：本轮是**方法轮**，不新增外部事实；榜单与接口数字全部沿用第 1 轮检索（2026-11-17，teaser/占位表口径）。若下一轮要主张"轨迹投影在同类赛事中无人做"，必须先检索确认，本轮不作此主张。

## 0. 一句话本轮转向

第 1 轮回答"每个模块**做什么**"；第 2 轮回答"模块之间**用什么货币交换**、动作在最后一厘米**怎样被几何地修正**"。答案：把交换货币从"原始动作块"换成**带前后条件的约束轨迹原语**，并引入一个**只做投影、不做发明**的轻量轨迹优化器作为唯一动作出口。

## 1. 直觉与动机

### 灵感 1 ·「轨迹优化」——最后一厘米不是"预测得更准"，而是"在可行域里投影"

**直觉**：VLA 的强项是"看懂该往哪去"，弱项是"保证这一步物理可达、平滑、不撞、能插进去"。第 1 轮已确认榜单最难的任务集中在插入/旋转/细粒度摆放（Plug In Ethernet 17.7、Unlock 20.1、Open Pill Bottle 22.7），这些任务的共同要求是 **1–2 mm 级末端对齐 + 姿态约束 + 接触维持**；而 chunk 式动作生成恰好在 chunk 边界与接触瞬间最不连续。继续"训一个更大的策略"是用语义能力补几何精度，属于工具错配。

**第一性原理**：**生成（generation）与投影（projection）是两种不同运算**。VLA 给出参考轨迹 `τ_ref`，它可能不可行、不光滑、边界跳变；轨迹优化在约束集 `C` 上求 `τ* = Proj_C(τ_ref)`，只把参考轨迹修正到"最近的可执行轨迹"。它不需要重新理解任务，只需要一个运动学模型、一个约束集、一个可微的跟踪代价。这与第 1 轮 IP-03 的 chunk 缝合同构，但层级更高：缝合只补 C0/C1 连续性，投影补**可行性、碰撞、接触与目标**。

**必须接受的硬约束**（否则就是空想）：不上重型 MPC，不做在线动力学辨识。用**任务空间/关节空间双积分器 + 关节限位 + 速度/加速度界 + 深度点云碰撞代理 + 抓握刚性约束**的短时域（H≈8–16）iLQR/QP，目标 2–5 ms 可解；只在 align/insert/release 相位触发，避开全时延压力。

### 灵感 2 ·「模块化设计」——模块化不是"分文件夹"，是"可替换且可归因"

**直觉**：第 1 轮的栈（接地/技能/适应/工程）在架构图上很清楚，但工程上很容易退化成"一坨代码里互相偷看变量"：抓握模块偷读技能模块的相位、缝合器直接改动作专家输出、适配器悄悄污染主干。这样的"模块"既不能单独消融，也不能在故障时安全退化。

**第一性原理**：模块化的本质是**契约**。每个模块声明输入/输出 schema、前置/后置条件、时延上界、失败回退；组合算子 `⊗` 只在 `Post_i ⇒ Pre_j` 时有定义。契约稳定后，才能做三件第 1 轮做不到的事：**(a) 单模块替换的边际价值可测**（把模块换成恒等/回退，看性能掉多少）；**(b) 故障被隔离在契约边界**（回退到 fallback，而不是全局漂移）；**(c) 合规可审计**（哪些是可学习参数、哪些是确定性代码，一目了然）。

**与「轨迹优化」的化学反应**：**把轨迹原语当作模块间的唯一货币**。模块不再传"动作块"，而传"带前后条件的轨迹段"。抓握模块的后置条件是"物体随 EE 刚性运动"，运动模块的前置条件正是它——契约天然对齐；抓握失败会在接口处显式暴露，而不是被下游模块默默吸收。

### 合成：TPI（Trajectory-Primitive Interface，轨迹原语接口）

**以轨迹原语为接口的模块化栈**：感知/接地模块产出 `(grasp_state, object_pose ± σ)` → 技能模块产出参考轨迹原语 `τ_ref` → 轨迹优化模块投影为可行 `τ*` → 安全/审计模块限幅与记录。第 1 轮的 IP-02/IP-03/IP-06 被"重写接口"而非"增加组件"；IP-01 的专家输出也从"动作块"改为"轨迹原语"，从而可被同一优化器统一约束。**这不是往栈上再加一层，而是把层与层之间的缝换成可验证的契约。**

## 2. 从第 1 轮遗留问题到本轮抓手

第 1 轮留下三处未闭合的缝：

1. **抓握确认仍是黑箱分类器**（U4 的 `g_t`）。`τ_conf` 缺乏物理标定；漏判代价不对称（L3 只给了净收益条件，没给可观测的滑移信号）。
2. **chunk 缝合是后处理**（U7）。只能在边界补连续性，无法保证整段可行、无碰撞、能维持接触。
3. **模块边界未形式化**。P3（技能复用）与 Level-0…4 退化链无法被实验单独度量。

本轮用两个灵感逐一闭合：轨迹优化把 1、2 变成**同一个几何投影问题**；模块化设计把 3 变成**可测契约**。

## 3. 研究问题（Q6–Q10）

- **Q6（滑移可观测性）**：在腕部相机深度噪声 `σ_d` 与位姿估计噪声下，"物体相对 EE 的刚体残差"能否在 1–2 mm 级滑移上可靠检测？可检测下界如何随物体纹理/遮挡/工作距离变化？这决定 GraspFSM 的阈值能否被物理标定，而不是拍脑袋。
- **Q7（投影的净收益与反噬）**：把 VLA 参考轨迹投影到可行域是否**只会更好**？在什么条件下投影会把"自信但错误"的目标放大（例如把 5 mm 的语义偏差当成精确目标去对齐）？如何用"参考轨迹本身作为可行候选 + 代理成功门控"保证不劣化？
- **Q8（轨迹原语的可组合性）**：以轨迹原语为接口后，模块组合是否满足"后置⇒前置"的传递性？在 OOD（未见物体/遮挡）下契约违反率有多高？
- **Q9（模块化的可归因性）**：单模块回退的边际损失能否被稳定估计？哪些模块是"死重"（边际价值≈0）应当剪掉？
- **Q10（合规的单 checkpoint 充分条件）**：一个可学习 checkpoint + 若干确定性/冻结模块，是否满足"单模型通才"？边界在哪里（例如，离线用任务数据单独训练的专家算不算第二模型）？

## 4. 设计原则（在 P1–P6 上增补）

- **P7 生成与投影分离**：语义生成只由学习模块负责；几何可行性只由确定性优化器负责；两者不得互相替代。优化器**没有权力改变目标**，只有权力改变到达目标的方式。
- **P8 契约先于实现**：任何模块先写 `(schema, Pre, Post, latency, fallback)`，再写实现；跨模块只通过轨迹原语交换，禁止共享可变状态。
- **P9 投影必须带门控**：优化结果只有在"约束满足 + 代理目标改善 + 时延达标"三者同时成立时才替换参考轨迹，否则**恒等回退**（对应第 1 轮 L3 的保守介入）。
- **P10 单 checkpoint 可审计**：所有可学习参数必须能追溯到唯一 checkpoint；任何新增可训练模块若不能并入该 checkpoint，一律不得进入提交主线（对应 Q10）。

## 5. 最小可提交闭环（MVP2）与退化链

**MVP2 = IP-06（代理评测，保留） + IP-10（GraspFSM 滑移状态机） + IP-09（TrajRefine 投影器） + IP-11（ModuleContract 契约层） + 第 1 轮基线策略。**
排序理由：IP-10 给 IP-02 一个物理阈值；IP-09 给 IP-03 一个原理性替代（缝合成为投影的一个约束项）；IP-11 让两者可被单独消融与安全回退。IP-01 的 MoE 继续训练，但**输出改为轨迹原语**，等 IP-11 契约稳定后再接。

**退化链**（在 Level-0…4 上细化）：
- Level-5 轨迹优化器超时/无解 ⇒ 恒等回退到 `τ_ref`（IP-09 内建）；
- Level-6 滑移残差不可信（`σ` 过大）⇒ GraspFSM 退化为第 1 轮的二值 `g_t` 高阈值模式；
- Level-7 契约违反（`Post` 不满足）⇒ 该模块回退 `fallback`，并在审计中记一次 `contract_violation`；
- 其余沿用 Level-0…4。

## 6. 预期贡献

1. 给出**轨迹原语接口**的形式定义与组合语义，把第 1 轮的"三层栈"从架构图变成可替换、可归因、可合规审计的模块图。
2. 把抓握确认从学习分类器升级为**有物理标定的滑移状态机**，给出可检测下界与噪声敏感性分析。
3. 给出**带门控的轨迹投影**，在明确假设下证明它不劣于参考轨迹，并量化其在插入/旋转任务上的净收益。
4. 给出**模块边际价值**的测量协议，使"剪枝"从主观判断变成可预注册的实验（直接服务第 1 轮的修剪预案）。

## 7. 本轮最大风险

**一句话**：轨迹投影的收益完全建立在"物体位姿估计足够准"之上，而最后一厘米恰恰是遮挡最重、未见物体最多、位姿最不可信的地方——优化器可能把一个"自信但偏了 5 mm"的目标投影成一条**更平滑、更快、更精确地撞向错误位置**的轨迹，且因为它看起来更"良构"而更难被审计发现。

## 8. 下一轮迭代计划

- 先做 **E619（离线回放投影）与 E620（滑移检测）**：两者都不需要真机，能在 1–2 天内决定 IP-09/IP-10 是否值得上真机。
- 若 E620 显示腕部深度噪声使 2 mm 滑移不可检测，则**砍掉滑移状态机的细粒度部分**，只保留"接触事件 + 大滑移（>5 mm）"检测，把资源转回 IP-09。
- 若 E619 的投影在离线回放上端点误差下降 <20%，则 IP-09 降级为"仅边界平滑"，并重新评估其 2–5 ms 时延是否值得。
- 模块化（IP-11）无论结果如何都保留：它是消融与合规的基础设施，成本低、信息价值高。

## 0. 本轮结论摘要

**一句话路线**：把模块间的"动作块"货币换成**带前后条件的轨迹原语**，并用一个**只做投影、带恒等回退**的轻量轨迹优化器作为唯一动作出口；抓握确认因此获得物理滑移信号，chunk 缝合升级为可行性约束，模块化因此可消融、可回退、可审计。

三条本轮新增的可检验主张：

| 主张 | 形式 | 检验 |
|---|---|---|
| 投影不劣化（条件性） | 若 `τ_ref` 始终是可行候选且门控要求代理成功不降，则 `τ*` 在约束满足时至少不差于 `τ_ref` | L10 / E619 |
| 滑移可检测（有下界） | 刚体残差 `> κσ` 时可检测；`σ` 由深度噪声与位姿估计误差决定 | L9 / E620 |

## 2. 创新点详述（本轮新增/重构）

### IP-09 · TrajRefine 约束轨迹投影（P0，新增）

- **动机**：第 1 轮已把断点定位在最后一环（插入/旋转/细粒度摆放）。这些任务的失败不是"不知道该做什么"，而是参考动作在接触附近不可行、不连续、不满足姿态约束。第 1 轮 IP-03 的缝合只处理 C0/C1，无法处理碰撞、关节限位、接触维持与目标对齐。
- **与现有方案的差异**：常见做法是"训练一个更大的 VLA 端到端输出动作"，把几何可行性交给数据覆盖；我们保留 VLA 的语义生成，但增加一个**确定性投影层**，把参考轨迹投到可行域。与"纯 MPC / 纯视觉伺服"的差异：我们不替换策略，只修正策略输出的最后一段；**优化器没有目标生成权**。
- **形式化**：见 U13/U14。核心是 `τ* = argmin_{τ∈C} J(τ; τ_ref)`，其中 `C` 含关节限位、速度/加速度界、碰撞代理、抓握刚性约束；`J` 含跟踪、平滑、目标与碰撞惩罚。用短时域 iLQR（2–3 次迭代）或 QP 求解。
- **关键设计（防反噬）**：
  1. **`τ_ref` 永远作为候选**：若 `τ_ref` 可行且门控不通过，直接返回 `τ_ref`（恒等回退）。
  2. **不确定性加权**：物体位姿标准差 `σ_p` 大时，增大跟踪代价 `Q` 的容差、降低目标项权重，让优化器**不要过度相信**一个高不确定目标；`σ_p` 超过阈值则只做平滑，不做目标对齐。
  3. **相位门控**：只在 align/insert/release 触发；reach/transport 用原策略，避免全局时延。
  4. **chunk 语义修正**：第 1 轮 U8 的"运行时自适应 chunk 长度"与 metadata 的静态 `action_chunk_size` 声明可能冲突。本轮改为：**声明 `T_max`，返回 `≤T_max` 的有效步 + 安全填充**（尾部减速/重复）；是否允许变长返回，由 Q5 的官方 client 复刻确认后再启用。
- **技术可行性**：中–高。运动学模型不需要 G1 动力学；碰撞代理可用深度点云或桌面包围盒；`H=8–16`、2–3 次 iLQR 在 JAX/C++ 下 2–5 ms 可达。真正的难点是**物体位姿估计**，不是优化器本身。
- **所需资源**：数据 = 官方 32 数据集（离线回放）+ 少量真机；算力 = 单卡 CPU/GPU 推理；接口 = 仍是单 `get_action`，返回 chunk。
- **落地步骤**：①用官方数据回放参考轨迹，离线跑投影，测端点误差/jerk/约束违反；②实现不确定性加权与门控；③复刻官方 client 确认 chunk 语义；④在 align/insert 相位接入；⑤真机 A/B（E622）。
- **风险**：①位姿估计误差被放大（本轮最大风险）；②优化器在接触时无解（刚性抓握约束与碰撞约束冲突）⇒ 软化约束、优先保持抓握；③额外时延 ⇒ 只在末段触发 + 时延预算硬门控。

### IP-10 · GraspFSM 滑移状态机（P0，深化 IP-02）

- **动机**：第 1 轮 U4 的 `g_t` 是单帧二值倾向，无法区分"夹爪闭合但没夹住"、"夹住后滑移"、"已经掉落"。而漏判代价不对称：以为抓住、其实没抓住，会让机器人带着空夹爪走到超时。
- **与现有方案的差异**：把抓握确认从"分类器 + 阈值"升级为**带物理残差驱动的时序状态机**；状态转移由 `(g_cmd, g_actual, 刚体残差 r_t, 接触代理)` 共同守卫。滑移残差直接来自"物体相对 EE 的位姿是否保持刚性"，与 IP-09 共用位姿估计与轨迹信息。
- **形式化**：见 U15/U16。
- **技术可行性**：中–高。残差计算复用 IP-10 的腕部特征与 6D 位姿头；若位姿头太贵，退化为 2D 光流残差（更便宜，但只在图像平面可观测）。
- **所需资源**：数据 = 官方数据 + 合成滑移注入；算力 = 小；接口 = 无新增。
- **落地步骤**：①定义刚体残差与噪声模型；②在官方数据上做合成滑移注入，测可检测下界；③训练/标定位姿头与 `σ_p`；④实现状态机与转移守卫；⑤真机 A/B（E622）。
- **风险**：①深度噪声使 2 mm 滑移不可检测 ⇒ 只保留粗粒度滑移；②位姿估计在遮挡下漂移 ⇒ `σ_p` 门控 + 回退到二值模式；③状态机抖动 ⇒ 最小驻留时间与滞回。

### IP-11 · ModuleContract 契约层（P0，新增）

- **动机**：第 1 轮的模块边界未形式化，导致无法单独消融、无法安全退化、无法向组委会解释"单模型"。
- **与现有方案的差异**：多数提交是单体脚本；我们把模块化做成**可执行契约**：输入/输出 schema、`Pre/Post`、时延上界、`fallback`。契约违反会被审计记录并触发回退，而不是静默传播。
- **形式化**：见 U17/U18。
- **技术可行性**：高（工程活）。
- **所需资源**：接口 = 无；算力 = 极小。
- **落地步骤**：①定义轨迹原语 schema 与 `Pre/Post` 谓词；②实现 `Module` 包装器与 `compose` 校验；③为每个模块写 `fallback`；④实现契约违反审计；⑤用"单模块替换"实验测边际价值（E624）。
- **风险**：①契约过粗 ⇒ 模块间仍偷看状态；过细 ⇒ 僵化。折中：接口只到"轨迹段"粒度，段内允许模块自治；②`fallback` 本身有 bug ⇒ `fallback` 必须是最简、可单测的恒等/安全动作。

## 3. 符号与定义（U13–U18）

| 符号 | 含义 |
|---|---|
| `τ` | 轨迹原语：带时间戳的位姿/关节序列 + 夹爪开合 + 接触模式 + 前后条件 |
| `C` | 可行约束集（关节限位、速度/加速度界、碰撞代理、抓握刚性） |
| `Proj_C(·)` | 到 `C` 的投影算子（带门控） |
| `J(τ; τ_ref)` | 投影代价（跟踪 + 平滑 + 目标 + 碰撞） |
| `r_t` | 滑移残差：物体相对 EE 的刚体偏差 |
| `s_t` | 抓握状态（FREE/APPROACH/CLOSING/HELD/SLIPPING/LOST/RELEASING/FAILED） |
| `M_i` | 模块：`(I, O, Pre, Post, impl, fallback, L_max)` |
| `⊗` | 模块组合算子 |
| `Δ_i` | 模块 i 的边际价值（回退后性能损失） |

**定义 U13（轨迹原语）** 轨迹原语是一个七元组
`τ = (x_{0:H}, g_{0:H}, c_{0:H}, Δt, Pre, Post, t_ref)`，
其中 `x_k ∈ R^d` 为声明控制空间（`joint` 或 `ee`）下的位姿/关节，`g_k ∈ [0,1]` 为夹爪开合，`c_k ∈ {free, contact, held, inserted}` 为接触模式，`Pre/Post` 是关于世界状态的谓词，`t_ref` 为生成时刻（用于时延核算）。轨迹原语是模块间**唯一**的动作货币。

**定义 U14（带门控的约束投影）**
`τ* = G( Proj_C(τ_ref) )`，其中
`Proj_C(τ_ref) = argmin_{τ∈C} J(τ; τ_ref)`，
`J = Σ_k ‖x_k − x_k^ref‖²_Q + λ_s Σ_k ‖u_k − u_{k−1}‖² + λ_g‖x_H − x^g‖² + λ_c φ_coll(x_k)`，
`u_k = (x_{k+1} − x_k)/Δt`；
门控 `G(τ) = τ` 当且仅当 `τ∈C`、`S(τ) ≥ S(τ_ref) − ε`、`latency ≤ L_max`，否则 `G(τ) = τ_ref`。`S` 为代理成功分（端点误差 + 约束裕度 + 姿态对齐），`Q` 随物体位姿不确定度 `σ_p` 增大而"软化"（增大容差、降低目标项权重）。

**定义 U15（滑移残差）** 在抓握建立时刻 `t0` 估计 `X = T_ee(t0)^{−1} T_obj(t0)`；对 `t > t0`，
`r_t = ‖ log_SE3( (T_ee(t) X)^{−1} T_obj(t) ) ‖_twist`。
`r_t` 在刚性抓握下仅含估计噪声；当 `r_t > κ σ_t` 且连续上升时判为滑移。`σ_t` 由深度噪声与 6D 位姿估计误差传播得到。

**定义 U16（抓握状态机）** 状态集 `S = {FREE, APPROACH, CLOSING, HELD, SLIPPING, LOST, RELEASING, FAILED}`，转移由 `(g_cmd, g_actual, r_t, c_k, n_retry)` 守卫：
- `CLOSING → HELD`：`g_cmd=closed`、`|g_actual−g_cmd|≤ε_g`、`r_t ≤ κσ` 持续 `w` 帧；
- `HELD → SLIPPING`：`r_t > κσ` 且 `r_t − r_{t−1} > 0` 持续 `w` 帧；
- `SLIPPING → LOST`：`r_t > κ'σ`（`κ'>κ`）或 `g_actual` 张开；
- `LOST → APPROACH`：`n_retry < 3`；否则 `→ FAILED`。

第 1 轮的 U6（高精度低召回介入）作为 `SLIPPING` 上的动作策略保留。

**定义 U17（模块契约与组合）** 模块 `M = (I, O, Pre, Post, impl, fallback, L_max)`。组合 `M_1 ⊗ M_2` 有定义当且仅当 `O_1 ⊆ I_2` 且 `Post_1 ⇒ Pre_2`。运行时若 `Pre` 或 `Post` 不满足，执行 `fallback` 并记一次 `contract_violation`。整个策略是一个以轨迹原语为边的 DAG，总时延上界为路径上 `L_max` 之和。

**定义 U18（模块边际价值）** `Δ_i = E_{D}[ S(system) − S(system with M_i → fallback_i) ]`，`D` 为评测分布（代理评测 + 真机抽样）。若 `Δ_i` 的置信区间包含 0 且上界 ≤ δ（如 0.2 成功分），判为"死重"并进入剪枝候选。P3 的复用约束改写为：每个可学习技能专家须在至少 2 个任务上 `Δ>0`。

```python
# ===== U13/U14：轨迹原语 + 带门控的约束投影（IP-09）=====
from dataclasses import dataclass

@dataclass
class TrajPrimitive:
    x: np.ndarray        # [H, d]  joint 或 ee（扁平化）
    g: np.ndarray        # [H]     夹爪开合
    c: np.ndarray        # [H]     接触模式（int）
    dt: float
    pre: dict
    post: dict
    t_ref: float

class TrajRefine:
    def __init__(self, H=10, kappa=3.0, d_safe=0.01, iters=3, sigma_max=0.004):
        self.H, self.kappa, self.d_safe, self.iters = H, kappa, d_safe, iters
        self.sigma_max = sigma_max

    def project(self, tau_ref, obs, sigma_p):
        C = self.build_constraints(obs, sigma_p)          # U14 的 C
        tau = tau_ref
        # 1) 参考轨迹不可行时才优化；否则直接作为候选
        if not C.feasible(tau):
            tau = self.ilqr(tau_ref, C, self.iters)        # 短时域 2-3 次
        # 2) 无解 / 超时 ⇒ 恒等回退（Level-5）
        if not C.feasible(tau):
            return tau_ref, "infeasible_fallback"
        # 3) 不确定性门控：σ_p 大 ⇒ 只平滑，不追目标
        if sigma_p > self.sigma_max:
            tau = self.smooth_only(tau_ref)
        # 4) 代理成功门控（P9 / L10）
        if not self.gate(tau, tau_ref, obs):
            return tau_ref, "gate_reject"
        return tau, "ok"

    def build_constraints(self, obs, sigma_p):
        return Constraints(
            q_lo=obs["q_min"], q_hi=obs["q_max"],
            v_max=self.v_max, a_max=self.a_max,
            sdf=obs["collision_sdf"], d_safe=self.d_safe,
            grasp_rigid=(obs["grasp_state"] == "HELD"),
            sigma_p=sigma_p,
        )

    def ilqr(self, tau_ref, C, iters):
        tau = tau_ref
        for _ in range(iters):
            tau = self._backward_pass(tau, C)   # 代价 + 约束线性化
            tau = self._forward_pass(tau, C)    # rollout + 投影到 C
        return tau

    def gate(self, tau, tau_ref, obs):
        return (self.constraints_ok(tau)
                and self.proxy_success(tau) >= self.proxy_success(tau_ref) - self.eps
                and self.latency_ok())
```

```python
# ===== U15/U16：滑移残差 + 抓握状态机（IP-10）=====
class GraspFSM:
    def __init__(self, kappa=3.0, kappa2=5.0, w=3, eps_g=0.02):
        self.kappa, self.kappa2, self.w, self.eps_g = kappa, kappa2, w, eps_g
        self.state = "FREE"; self.X = None; self.buf = []; self.prev_r = 0.0

    def step(self, obs):
        g_cmd = obs["gripper_cmd"][-1]
        g_act = obs["gripper_actual"][-1]
        r, sigma = self.slip_residual(obs)       # U15
        self.buf = (self.buf + [r > self.kappa * sigma])[-self.w:]
        rising = r > self.kappa * sigma and r > self.prev_r

        if self.state == "CLOSING":
            if g_cmd < self.eps_g and abs(g_act - g_cmd) <= self.eps_g and all(self.buf):
                self.state = "HELD"; self.X = self.relative_pose(obs)
        elif self.state == "HELD":
            if rising and all(self.buf): self.state = "SLIPPING"
        elif self.state == "SLIPPING":
            if r > self.kappa2 * sigma or g_act > self.eps_g: self.state = "LOST"
        elif self.state == "LOST":
            self.state = "APPROACH" if self.n_retry < 3 else "FAILED"
        self.prev_r = r
        return self.state

    def slip_residual(self, obs):
        # r_t = || log_SE3((T_ee(t) X)^-1 T_obj(t)) ||，X 为抓握建立时的相对位姿
        T_pred = obs["T_ee"] @ self.X
        r = se3_log_norm(inv(T_pred) @ obs["T_obj"])
        return r, obs["sigma_obj"]
```

```python
# ===== U17/U18：模块契约 + 组合 + 边际价值（IP-11）=====
class Module:
    def __init__(self, name, pre, post, impl, fallback, L_max):
        self.name, self.pre, self.post = name, pre, post
        self.impl, self.fallback, self.L_max = impl, fallback, L_max

    def __call__(self, inp, state):
        if not self.pre(inp, state):
            return self.fallback(inp, state), "pre_violation"
        out = self.impl(inp, state)
        if not self.post(out, state):
            return self.fallback(inp, state), "post_violation"
        return out, "ok"

def compose(m1, m2):
    assert m2.pre_implied_by(m1.post), f"contract mismatch: {m1.name} -> {m2.name}"
    return Module(
        name=f"{m1.name}⊗{m2.name}",
        pre=m1.pre,
        post=m2.post,
        impl=lambda x, s: m2(m1(x, s)[0], s)[0],
        fallback=lambda x, s: m2(m1.fallback(x, s), s)[0],
        L_max=m1.L_max + m2.L_max,
    )

def marginal_value(system, module_name, D, fallback):
    base = evaluate(system, D)
    ablated = evaluate(replace(system, module_name, fallback), D)
    return base - ablated
```

## 5. 推导（L8–L11）

**引理 L8（组合可行性传递）** 设 `M_1, M_2` 契约诚实（无隐藏状态、输出只由输入与声明状态决定），且 `Post_1 ⇒ Pre_2`。则对任意满足 `Pre_1` 的输入，`M_1 ⊗ M_2` 的输出满足 `Post_2`。
**证明**：`Pre_1` ⇒ `M_1` 输出满足 `Post_1`（契约诚实）⇒ 满足 `Pre_2` ⇒ `M_2` 输出满足 `Post_2`。对 DAG 归纳即得整条链路。∎
*注*：若模块共享可变状态或偷读邻居变量，契约诚实性被破坏，引理不成立——这正是 P8 禁止共享可变状态的原因。

**引理 L9（滑移可检测下界）** 在刚性抓握下 `r_t` 只含估计噪声。设物体位置估计误差标准差为 `σ_p`、姿态误差为 `σ_θ`、特征点到 EE 的距离为 `d`，则 `σ_r ≈ sqrt(σ_p² + (d σ_θ)²)`。采用 `κ` 倍阈值时，单次判定可检测的最小滑移量 `m* ≈ κ σ_r`。取 `κ=3`、`σ_p≈1 mm`、`d σ_θ≈0.5 mm`，得 `m* ≈ 3.4 mm`；只有在近距离（`σ_p≈0.5 mm`）且纹理丰富时才能逼近 2 mm。
**结论：1 mm 级滑移在通用条件下不可靠；GraspFSM 必须把"细粒度滑移"与"粗粒度滑移/掉落"分开设定阈值。** ∎

**引理 L10（门控投影不劣化，条件性）** 设 `τ_ref ∈ C`，`S` 为代理成功分。若 `Proj_C` 以 `τ_ref` 为可行候选（即 `J(τ*) ≤ J(τ_ref)`），且门控 `G` 仅在 `S(τ*) ≥ S(τ_ref) − ε` 时接受 `τ*`，则输出 `τ_out` 满足 `S(τ_out) ≥ S(τ_ref) − ε`。若 `S` 在目标任务族上单调于真实成功率，则真实成功率不降（最多 `ε`）。∎
*注*：这是**条件性**结论。若 `S` 在 OOD 上失准（例如把"对齐到错误目标"误判为高 `S`），门控会放行错误投影——这是本轮最大风险的形式化表述。缓解：`σ_p` 大时令 `S` 的目标项权重趋零（退化为只平滑），并保留 `τ_ref` 作为最终候选。

**引理 L11（单 checkpoint 合规的充分条件，非定理）** 若提交系统的全部可学习参数都包含在唯一 checkpoint `θ` 中，其余模块为**无参数确定性变换**或**未在任务数据上单独训练的冻结预训练组件**，则系统在"单模型"意义上可被解释为一个模型。∎
*注*：这不是数学定理，而是**合规论证的充分条件**；"冻结预训练组件是否算第二模型"必须由组委会书面确认（Q10）。若不允许任何外部冻结组件，则退回"仅 `θ` + 确定性代码"的最严格形态，并实测其性能损失（对应第 1 轮 E611）。

## 11. 本轮最值得押注的创新点（一句话）

**押注 IP-09 + IP-10 的组合：轨迹投影负责最后一厘米的几何可行性，滑移状态机负责接触真相；两者共享同一套位姿/轨迹信号，正好把"模型几乎做对了"变成"系统能在最后一厘米判断自己是否正在失败并修正"。**

**本轮最大风险（一句话）**：轨迹投影的收益完全建立在"物体位姿估计足够准"之上，而最后一厘米恰恰是遮挡最重、未见物体最多、位姿最不可信的地方——优化器可能把一个"自信但偏了 5 mm"的目标投影成一条更平滑、更快、更精确地撞向错误位置的轨迹，且因为它看起来更"良构"而更难被审计发现。
