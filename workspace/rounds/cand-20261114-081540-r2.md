# 第 73 轮（承接第 72 轮「EMBODIED-GAUGE-RAS 具身计量审计×实时执行图×意图×灵巧操作」IP-287~294；灵感循环第 3 轮；本轮灵感：「需求洞察」×「跌倒恢复」）

> R72 把 GAUGE-RAS 从「认知层算法」下沉为「具身系统」：REG 实时执行图把「计量不阻塞控制」变成调度级定理；IRL 把意图 z 引入联合后验 b_t(s,z)；DMEM 把灵巧手触觉升级为接触模式条件的计量证据；EREFLEX/ERVOI/E-RISK 把情感、意图、接触三层反作用合算；S2R-UQ 把 sim2real 残差传播到 WCET 与 λ_floor。R72 的核心姿态是：**「在标称工况下，我的测量链在实时调度里仍能逐指令兑现风险界。」**
>
> 但 R72 有两个未言明的前提，恰好被本轮两个灵感词击穿：
> - **需求洞察视角**：R72 的 z 是「人要我做什么动作」，不是「人真正需要什么」。意图与需求是多对一的：同一句「帮我拿水」可能对应口渴、噎住、想站起来、害怕跌倒、只是礼貌性试探。R72 优化 z，可能**正确地执行了一个错误的需求**；更糟的是，需求是隐性的、会被社会性掩饰、依赖人的能力、且**会被失败揭示**。把「需求」当作「意图的别名」，会让风险分母漏掉最大的一项：**需要错位（need misalignment）**。
> - **跌倒恢复视角**：R72 的证书是在「人站立、协同、传感器不饱和、接触近似高斯」的标称 regime 里证的。但跌倒/近跌倒是**稀有、高冲击、传感器饱和、截止时间骤缩、后果不可逆**的尾部事件——它不是「更大的噪声」，而是**证书的相变点**：同一个 J_EMB，在跌倒 regime 里可能一字不成立。R72 的连续风险缩放（λ↑ ⇒ 软化）也无法处理「安全集与当前状态不连通」的情形（人已倒地、机器人已失稳）。
>
> 本轮把 R72 的「具身计量审计」推进到 **CARE-GAUGE-RAS**（Consent-gated, Authentic-need, Recovery-regime, Epistemic-rupture GAUGE for RAS）——**工况绑定、需求洞察、同意门控、断裂隔离、恢复优先的照护型计量审计闭环**。核心命题：**不再只问「标称工况下测量链可信吗」，而问「当人真正需要的与嘴上说的不一致、当系统/人正在跌倒、当旧模型瞬间失效时，系统能否先停住、再救、最后才谈优化？」**
>
> 关键转向：
> 1. **从 intent 到 need**：区分 b_t(z) 与 b_t(n)；引入需求证据（自述/行为/能力/语境/后果）、需求校准、需要错位代价、自主性代价；需求不确定度进入伤害而非只进入 λ。
> 2. **从频率分离到 regime 分离**：r ∈ {NOMINAL, ATTENTIVE, CRITICAL, RECOVERY, POST}；证书/后验必须带 regime 标签与有效性包络 D_r；跨 regime 即失效。
> 3. **从降权到隔离（quarantine）**：epistemic rupture 时不再「把旧似然乘个 0.2」，而是**把旧后验隔离、退回保守先验**，因为被污染的结构会继续自信。
> 4. **从连续缩放到离散逃逸**：λ 有上限；当连续安全集不可达时，必须切换到**预认证的恢复原语**（brace/freeze/roll/call-help），用 minimax 而非 expected value。
> 5. **从绩效到同意**：同意是硬约束，不是代价项；需求再大也不能越过「明确拒绝 / 预立医嘱」。

## 0. 直觉与动机

**灵感 1（需求洞察 → 意图是「要什么动作」，需求是「为什么需要这个动作、怎样才算被帮助」）**
直觉：人说「把那个给我」，这是一个**意图 z**；但驱动这句话的可能是口渴、可能是想支开你、可能是够不着、可能是想测试你、也可能是即将跌倒想抓个支撑。需求 n 是**多对一映射到意图**的隐变量，而且它有五个特征：
- **隐性**：最紧迫的需求往往不说（噎住的人不会说「我噎住了」；认知障碍者无法表述）；
- **多维且部分有序**：安全 > 健康 > 任务 > 社交 > 自主性，但权重因人、因时、因文化而异（Kano 模型里的「基本型/期望型/兴奋型」需求在照护里对应「保命/减负/尊严」）；
- **自述有偏**：社会赞许性、隐忍、怕麻烦人、认知负荷都会稀释「我没事」这句话的信息量；
- **能力依赖**：同一个需求，能力不同则所需帮助完全不同（能自己站 vs 需两人扶 vs 只能呼叫）；
- **会被后果揭示**：一次跌倒会比一百句自述更清楚地暴露「高估了自己的能力」。
把需求当意图，会让机器人陷入**「正确地执行错误目标」**：它把水递到噎住的人手里，动作完美、时机精准、证书齐全，但伤害最大。**需求洞察不是更细的分类，而是从「动作目标」升维到「人的状态与价值排序」。**

**灵感 2（跌倒恢复 → 尾部事件不是更大的噪声，而是测量模型的相变点）**
直觉：R72 的整套证书假设「噪声近似高斯、接触可控、时间充裕、后果可逆」。跌倒是这套假设的**同时失效**：
- **稀有**：单帧跌倒先验可能只有 10⁻⁴~10⁻⁶，检测器的 AUROC 再高，部署 PPV 也可能低到个位数——这是医学筛查里著名的**基率谬误**；
- **高冲击**：加速度饱和、触觉阵列削顶、力矩尖峰，Σ_c 的高斯假设直接不成立；
- **截止时间骤缩**：从「50ms 计量审计」变成「100–300ms 内必须制动/支撑/呼叫」；
- **不可逆**：一次错误的「扶」可能造成二次伤害，一次错误的「等」可能错过黄金时间；
- **模型整体失效**：跌倒瞬间，「人是站立的、合作的、有能力的」这一整套先验同时为假。
因此正确反应不是「把 Σ 调大一点、把 λ 抬高一点」，而是**宣布旧 regime 失效、隔离旧后验、切换到恢复原语**。**跌倒恢复的本质不是更强的估计，而是更快的「放弃旧模型」与更保守的「先安全后理解」。**

**灵感 3（regime 即语义 → 证书必须绑定工况，跨工况即失效）**
直觉：J_EMB 像一张「平静水域适航证」。船进了风暴，证还在，但它什么都没保证。R72 的证书没有 regime 字段，于是系统会**带着标称证书进入恢复工况**，事后审计发现「证书当时有效」。必须把 `regime_tag` 与有效性包络 `D_r` 写进证书：在 r 内、在 D_r 内，证书才成立；一旦 `innovation` 越出 D_r（epistemic rupture），证书**立刻作废**，不是降权，而是作废。**「有效性域」不是统计置信区间，而是模型的适用边界；越界后的正确动作是停机/降级，不是继续贝叶斯。**

**灵感 4（需求与失败耦合 → 失败既暴露需求，也摧毁模型）**
直觉：跌倒同时是两件事的证据：(a) 关于人的需求（脆弱性、环境风险、能力高估）；(b) 关于机器人模型的错误（需求模型错、风险模型错、检测器错）。但「世界变了」与「我模型错了」在单次失败里**不可分辨**。朴素贝叶斯会把两者混成一个后验更新，结果要么过度自责（把一次偶然当系统性错误），要么过度外归因（把系统性缺陷当意外）。需要**断裂归因（rupture attribution）**：world-change / model-wrong / sensor-fault / unknown，默认 unknown → 走保守路径；结构性更新（新增需求类别、修改安全约束）必须离线复核后才能用于高力动作。**失败是最好的老师，但也是最危险的老师。**

**灵感 5（连续缩放的极限 → 安全集可能不连通，必须离散逃逸）**
直觉：R72 的 λ↑ ⇒ 软化阻抗/降速，隐含假设「安全是一个连续可调的量」。但有些情形下，**当前状态根本不在连续控制可达的安全集里**：人已经倒地，机器人还在伸手；机器人已经失稳，任何连续力矩都救不回来。此时继续增大 λ 只会「优雅地摔」。正确做法是切换到**预认证的离散恢复原语**（brace / compliant-collapse / roll / call-help），用**最坏情况最小化**而不是期望最优。**连续缩放负责「别出事」，离散原语负责「已经出事了怎么收场」。**

## 1. 形式化定义（增量：定义 366–384）

**定义 366（CARE-GAUGE-RAS 总览与六不变式）** CARE-GAUGE-RAS = (NIL, FRR, RQM, RPRIM, CONSENT, NHARM, RVOI, GAUGE-RAS††)。六不变式：
(i) **regime 绑定有效性**：每个后验/证书携带 regime 标签 r ∈ ℛ 与有效性包络 D_r；跨 regime 未复证即失效；
(ii) **need–intent 分离**：b_t(n) 与 b_t(z) 独立建模；需求证据必须含能力 cap、语境 x、后果 o；需求不确定度与需要错位进入**伤害**，不只进入 λ；
(iii) **同意优先**：可行动作集 A_t ⊆ A_auth(consent_t)；任何需求后验都不能扩张该集合；
(iv) **恢复字典序优先**：在 CRITICAL/RECOVERY 中，目标按字典序 =（最坏伤害 → 到安全态时间 → 需求满足 → 信息增益）；信息获取仅在**不消耗恢复截止时间**时允许；
(v) **断裂隔离**：innovation 越出 D_r 即触发 quarantine，禁止用旧似然继续锐化后验；退回保守先验与恢复策略；
(vi) **严格退化链**：CARE ⇒ EMBODIED（R72）⇒ GAUGE（R71）⇒ R68，逐指令等价，安全侧只增不减。

**定义 367（潜在需求模型 NIL）** 需求 n = (n_safe, n_health, n_task, n_social, n_autonomy) ∈ 𝒩，分为**硬需求** 𝒩_hard（人身安全、同意）与**软需求** 𝒩_soft（舒适、效率、社交、自主）。后验
b_t(n) = p(n | ℋ_t, cap_t, x_t)，
其中 cap_t 为人的能力估计（站立/握力/认知/疲劳），x_t 为语境。需求转移
p(n_{t+1} | n_t, a_t^robot, o_t)
显式含**后果 o_t**：需求会被「上一次帮助的结果」改变。关键性质：**p(n | z) 一般非单射**（定义 368 引理 35），故仅凭意图证据不可识别需求。

**定义 368（需求证据与代价敏感校准）** 多模态需求证据 y_need = (y_self, y_beh, y_ctx, y_out)：
- y_self：自述（受社会赞许性/隐忍/认知障碍污染）；
- y_beh：行为/生理（步态、握力、语颤、呼吸、回避动作）；
- y_ctx：语境（时间、地点、任务、在场者）；
- y_out：上一个动作的后果（是否更稳、是否退缩、是否求助）。
证据模型 p_need(y_need | n, z, ψ, x) = Σ_k ω_k(ψ, x) · p_k(y_need | n, z)。输出
(n̂, b_t(n), ECE_need, cov_hard, ι_need, FNR_need(π), FPR_help(π), autonomy_cost)，
其中 FNR_need/FPR_help 必须**在部署基率 π 与子人群上报告**（老人/失能/跨文化）。代价矩阵 C_need(n̂, n) 非对称：漏掉硬需求 ≫ 过度帮助的社交代价，但**过度帮助不是零代价**（自主性/尊严/依赖）。

**定义 369（regime 状态机与 regime 后验）** r ∈ ℛ = {NOMINAL, ATTENTIVE, CRITICAL, RECOVERY, POST}：
- NOMINAL：常规协作；
- ATTENTIVE：跌倒风险升高（步态异常、环境危险、疲劳），预算收紧但任务继续；
- CRITICAL：跌倒进行中/即将发生/检测器已宣告；
- RECOVERY：机器人自恢复或对人施救；
- POST：已稳定，进入信任修复与需求重估。
转移 p(r_{t+1} | r_t, s_t, fall_risk_t, a_t)，附守卫条件。**regime 本身有后验 b_t(r)**；声明 regime r̂_t 与 b_t(r) 的失配率是核心指标。证书仅在 `r̂_t = r_cert` 且 `b_t(r_cert) ≥ 1 − ε_r` 时有效。

**定义 370（跌倒事件模型与基率校正检测证书）** 跌倒事件 f ∈ {none, human-fall, robot-fall, object-fall, near-miss}。检测采用**序贯检验**（SPRT/CUSUM）而非单帧分类，输出 (Se, Sp, E[τ_detect], τ_declare, α, β)。部署证书必须给出**基率校正 PPV**：
PPV(π) = π·Se / [π·Se + (1−π)(1−Sp)]。
只在 `PPV(π_L) ≥ τ_ppv`（π_L 为部署基率下界）时允许宣告；且**近跌倒是独立标签**（needs insight 的高价值证据，不可并入跌倒）。**AUROC 不是安全证据。**

**定义 371（regime 条件计量与 epistemic rupture）** 证据模型 p_r(y | s, c) 随 r 变（CRITICAL/RECOVERY 允许重尾、饱和、时延、丢帧）。定义 innovation e_t = y_t − h_r(ŝ_t)，断裂统计量
R_t = e_tᵀ Σ_r^{-1} e_t + 1[saturated] · M_s + 1[τ_sync > τ_sync^max] · M_t + 1[impulse > I_max] · M_i。
若 R_t > κ_r 或任一硬指标越界，则声明 **epistemic rupture**：p_r 不再可用。**注意：rupture 不是「噪声大」，是「模型不适用」。**

**定义 372（后验隔离滤波器 Q-filter）** 断裂时**禁止**用旧似然继续更新，改为
b_t^Q = Q(b_{t-1}, p_r) ∈ argmin_{b ∈ ℬ_safe} max_{p ∈ 𝒫_r} E_b[ℓ(s, a)],
即在**安全后验集合 ℬ_safe**（协方差膨胀、硬约束支撑集、或均匀覆盖）上取 minimax 鲁棒后验。非断裂时仍用贝叶斯更新。**隔离 vs 降权的区别**：降权仍保留旧模型的结构（会继续自信），隔离把旧结构从锐化路径中移除。

**定义 373（恢复原语库）** 预认证离散动作集
𝒜_rec = {(a, P_a, T_a^wc, H_a^wc, Q_a, auth_a, F_a^wc)}，
含 brace（支撑）、compliant-collapse（顺从倒地）、roll（翻滚）、push-up（撑起）、kneel（跪起）、crawl（爬行）、freeze（冻结）、call-help（呼叫）、light-assist（轻扶）、full-assist（全力扶）。属性：前置条件 P_a、最坏时长 T_a^wc、最坏伤害 H_a^wc、后置条件 Q_a、同意要求 auth_a、最坏接触力 F_a^wc。**所有原语离线预认证，在线只做选择，不现场发明。**

**定义 374（截止时间约束的 minimax 恢复选择）**
π_rec = argmin_{a ∈ 𝒜_rec} (H_a^wc, T_a^wc) 字典序，
s.t. T_a^wc ≤ T_deadline(r), P_a(s_t) 以高概率成立, auth_a(consent_t) 成立。
若可行集为空，选择 `brace/freeze`（**永远可行且 H^wc 有界**的兜底原语）。**恢复不做期望最优，因为期望所依赖的模型正是被断裂摧毁的那个。**

**定义 375（恢复价值 R-VoI 与「信息是负债」）** 恢复期价值是向量
RVoI(g) = (ΔH_harm, ΔT_safe, ΔH_need)，
按字典序比较，不做加权和。信息动作 g_info 仅在 `T(g_info) + T(recovery after) ≤ T_deadline` 且其最坏伤害不超过无信息方案时允许。定义**认知预算 B_epi(r)**：随紧迫度单调收缩；CRITICAL 中 B_epi ≈ 0。**平时「多问一句更安全」，跌倒时「多问一句会死人」。**

**定义 376（需求感知伤害与 λ 饱和 → regime 切换）** 伤害
H = H_safe + α·H_need-misalign + β·H_autonomy + γ·H_trust，
H_need-misalign = E_{n~b(n)}[C_need(n, plan(n̂))]，H_autonomy 为过度帮助的自主性代价。风险缩放扩展为
λ = max(λ_risk(U_ale, U_epi, H_z, u_tac), λ_floor(...), λ_need(H[b_t(n)], p(f)), λ_consent),
但设置**饱和上限 λ_max**。**关键定理（引理 34）**：若当前状态不在连续控制族 {π_λ : λ ≤ λ_max} 的 T_deadline-可达安全集内，则任何连续缩放都无法保证安全，必须切换到 𝒜_rec。**λ 负责「避免进入不可达区」，原语负责「已经在不可达区时怎么出来」。**

**定义 377（同意/授权模型）** 授权 a ∈ {yes, no, advance-directive, emergency-presumed, unknown}，后验 p(a | person, context, prior)。硬约束：
- `no` 或预立医嘱禁止 ⇒ 任何超过 F_light 的物理干预被**否决**；
- `unknown` ⇒ 只允许最小侵入动作（call-help / light-assist / freeze）；
- `emergency-presumed` 仅在**无法获得同意且不干预的伤害上界严格更大**时启用，且需事后审计。
**同意是不确定性不能被「需求更大」抵消的硬约束。**

**定义 378（失败揭示需求与断裂归因）** 跌倒/rupture 后对 (n, θ_model) 联合更新：
p(n, θ | f=1) ∝ p(f=1 | n, θ) p(n, θ)，
并允许**有界结构更新**（新增需求类别 n_new、修改风险模型），但结构更新须离线复核后才能驱动高力动作；在线只允许保守参数收缩。断裂归因
a_attrib ∈ {world-change, model-wrong, sensor-fault, unknown}，
默认 `unknown` → 保守路径。**单次失败不得独自改写安全约束。**

**定义 379（R-MIB 指标扩展）** 在 E-MIB 上新增：
- **需求族**：ECE_need、FNR_need(π)、FPR_help(π)、硬需求覆盖率 cov_hard、需要错位代价、自主性代价、ι_need（跨人群不变性）；
- **跌倒族**：Se、Sp、PPV(π_L)、E[τ_detect]、τ_declare、近跌倒召回、误报负担（每小时误报数）；
- **恢复族**：到安全态时间 T_safe、最坏伤害 H^wc、恢复成功率、再跌倒率、原语覆盖度、二次伤害率；
- **regime 族**：regime 失配率、证书失效率、rupture 检出延迟 τ_rupt、复证时间；
- **同意族**：硬否决正确率、越权干预率、emergency-presumed 审计通过率；
- **信任族**：自报置信校准、过度声称率、信任账户余额。
所有指标同遵循定义 332 六元组与定义 333 DAG 分层。

**定义 380（R-IVG 门控扩展）** 新增失效条件：
- 需求：ECE_need > τ_ece、FNR_need(π) > τ_fnr、cov_hard < τ_cov、H[b(n)] > τ_Hn、ι_need 报警；
- 跌倒：PPV(π_L) < τ_ppv、τ_declare > τ_declare^max、误报负担超阈；
- regime：失配率 > τ_mismatch、rupture 未在 τ_rupt 内检出；
- 恢复：无可行授权原语、H^wc > H_budget、deadline 不可满足；
- 同意：所需力 > F_light 且授权为 unknown/no。
任一成立 ⇒ 相关模块降级（需求失效 ⇒ 回退到「显式意图 + R72」；regime/恢复失效 ⇒ 保守停机/brace；同意失效 ⇒ 仅最小侵入）。

**定义 381（CARE 证书 J_RG）** J_RG = (J_EMB, regime_tag, regime_validity_proof, fall_detection_bound, need_validity, consent_validity, recovery_plan_proof, deadline_proof, trust_report, care_ver)。Valid ⇔ J_EMB 有效 ∧ 当前 regime 与 tag 匹配且 b_t(r) ≥ 1−ε_r ∧ PPV 界成立 ∧ 需求校准有效 ∧ 同意校验通过 ∧ 恢复计划在 deadline 内且已授权。

**定义 382（威胁模型 AIC-REC）** ℰ_REC = ℰ_EMB × ℰ_regime × ℰ_need × ℰ_fall × ℰ_consent：
- ℰ_regime = {regime 混淆、证书重放、rupture 洪水攻击（迫使系统长期保守=拒绝服务）、伪 rupture 触发重置}；
- ℰ_need = {需求隐瞒/伪装、对抗性需求诱导、利用文化差异的需求误读、利用「过度帮助」消耗信任}；
- ℰ_fall = {跌倒检测欺骗/规避、近跌倒也伪造、用假跌倒诱发紧急越权}；
- ℰ_consent = {同意伪造、预立医嘱篡改、紧急假定滥用}。
**新增攻击面本质：攻击者可以操纵「紧迫性」来绕过审慎。**

**定义 383（严格退化包含链）**
- 全有效 ⇒ CARE 完整形态；
- NIL 失效 ⇒ 显式意图 z + R72（仍保留 regime/恢复/同意）；
- regime 失配或 FRR 失效 ⇒ 退回 RQM 保守后验 + brace/freeze（不看需求、不做任务优化）；
- 同意不足且需高力 ⇒ 仅 call-help / light-assist；
- 上述全失效 ⇒ R68（纯开环/机械安全）。
**安全单调不减；但需求满足度在退化时主动下降——这是设计选择，不是缺陷。**

**定义 384（信任修复与恢复报告）** 恢复后必须产出校准报告 (发生了什么, 各判断的置信, 哪些模型被更新, 残余风险, 下次如何避免)，且**禁止过度声称**。定义信任负债 D_trust = 过度声称量 − 实际可靠性；D_trust 累积会触发「降级为更保守的交互」。**恢复不是回到原状，而是带着被修正的模型与受损的信任重新开始。**

## 2. 关键算法骨架

```python
# IP-295 NIL：需求洞察层（50Hz 计量域；不阻塞控制域）
class NeedInsightLayer:
    def __init__(self, need_net, calib, cost_matrix, consent_model):
        self.net, self.calib = need_net, calib
        self.C, self.consent = cost_matrix, consent_model
    def update(self, y_need, psi_hat, cap, ctx, outcome):
        # y_need = (self_report, behavior, context, last_outcome)
        logits = self.net(y_need, psi_hat, cap, ctx)      # ψ 调制：敷衍/隐忍会压低自述权重
        b_n    = self.calib.predict(logits)               # b_t(n), ECE_need, iota_need
        hard   = project_hard(b_n, ctx)                   # 硬需求支撑集（安全/同意）
        fnr, fpr, aut = self.calib.cost_report(b_n, self.C, prevalence=ctx.prevalence)
        return NeedPosterior(b_n=b_n, hard=hard, ece=b_n.ece, iota=b_n.iota,
                             fnr=fnr, fpr_help=fpr, autonomy_cost=aut)

# IP-296 FRR：regime 状态机 + 基率校正跌倒检测（序贯检验）
class FallRecoveryRegime:
    def __init__(self, hazard, sprt, regime_hmm, tau_ppv, tau_declare):
        self.hazard, self.sprt, self.hmm = hazard, sprt, regime_hmm
        self.tau_ppv, self.tau_declare = tau_ppv, tau_declare
    def step(self, sensors, cap, b_n):
        fall_risk = self.hazard(sensors, cap)
        n_tests   = self.sprt.update(sensors.fall_evidence)
        se, sp, delay = self.sprt.stats()
        ppv = base_rate_ppv(se, sp, sensors.prevalence_lower)
        declared = (ppv >= self.tau_ppv) and (delay <= self.tau_declare)
        r_post = self.hmm.step(sensors, fall_risk, declared)
        r_hat  = argmax_regime(r_post, hysteresis=H_R)    # 防抖，避免 regime 抖动
        return RegimeState(r_hat, r_post, fall_risk, ppv, delay, declared)

# IP-297 RQM：断链隔离滤波器（控制域 1kHz，<0.05ms）
def quarantine_update(b_prev, y, r, params):
    e  = innovation(y, r)
    Rt = e @ inv(params.Sigma_r) @ e
    rupture = (Rt > params.kappa_r) or saturated(y) or (params.sync_err > params.tau_sync)
    if rupture:
        # 不作降权，直接隔离：退回安全后验集合上的 minimax 鲁棒后验
        return minimax_safe_posterior(b_prev, params.mathcal_P), RuptureFlag(True, Rt)
    return bayes_update(b_prev, likelihood_r(y, r)), RuptureFlag(False, Rt)

# IP-298 RPRIM：预认证恢复原语 + 截止时间 minimax 选择
def select_recovery(regime, b_n, consent, env, T_deadline):
    cands = [a for a in PRIMS
             if robust_precond(a.P, env)
             and authorized(a, consent)                 # 同意硬门控
             and a.T_wc <= T_deadline]
    if not cands:
        return SAFE_FALLBACK                            # brace/freeze，永远可行
    # 字典序：最坏伤害 -> 最坏时长 -> 需求满足（不做期望）
    return min(cands, key=lambda a: (a.H_wc, a.T_wc, -need_gain(a, b_n)))

# IP-299 RVOI：恢复期价值（字典序，禁止「多问一句」拖延）
def recovery_voi(g, deadline, B_epi, b_n):
    if g.is_information:
        # 信息是负债：只有不消耗恢复截止时间才允许
        if g.T_wc > B_epi * deadline: return None
    return (g.delta_harm, g.delta_T_safe, g.delta_need)   # 字典序向量，非标量

# IP-300 NHARM：需求感知伤害 + λ 饱和触发恢复切换
def care_risk(U_ale, U_epi, H_z, u_tac, H_n, p_fall, consent_unc, params):
    denom = U_ale + U_epi + H_z + u_tac.total()
    lam = max(params.lam_base * (1 + denom / params.lam_scale),
              params.lam_floor * (1 + denom),
              params.lam_need * (1 + H_n + p_fall),
              params.lam_consent * (1 + consent_unc))
    lam = min(lam, params.lam_max)
    if lam >= params.lam_max or not continuous_safe_reachable(lam, params.T_deadline):
        return SWITCH_RECOVERY                          # 连续缩放已到天花板
    return lam

# IP-301 CONSENT：同意硬门控（先于需求、先于任务）
def consent_gate(action, auth):
    if action.F_wc <= F_LIGHT:
        return Allow(action)
    if auth.state in ('no', 'forbidden'):
        return Veto('explicit_or_directive')
    if auth.state == 'unknown':
        return Veto('unknown_high_force')               # 只允许最小侵入
    if auth.state == 'emergency-presumed':
        # 仅在「不干预的最坏伤害严格更大」时放行，且需事后审计
        return Allow(action) if action.H_noop_wc > action.H_wc + MARGIN else Veto('no_emergency')
    return Allow(action)

# IP-302 CARE 主闭环（在 R72 三域之上加 regime/need/consent 三闸）
def CARE_GAUGE_RAS_round(M, obs, audio, tac, sensors):
    # ===== 控制域 (1kHz, 硬实时) =====
    snap  = M.snapshot.read_latest()
    r     = snap.regime.r_hat
    b_s   = M.bse.step_ctrl(snap.b_prev, obs, M.last_action)      # R72
    U_ale, U_epi = decompose_ctrl(b_s, M.fmp, obs)
    H_z   = snap.z_dist.entropy() if snap.z_dist else 0.0
    u_tac = snap.tac_ev.u_tac if snap.tac_ev else 0.0
    H_n   = snap.need.entropy() if snap.need else 0.0
    lam_or_switch = care_risk(U_ale, U_epi, H_z, u_tac, H_n,
                              snap.fall_risk, snap.consent_unc, M.risk_params)
    if lam_or_switch == SWITCH_RECOVERY or r in ('CRITICAL', 'RECOVERY'):
        a_rec = select_recovery(r, snap.need.hard if snap.need else None,
                                snap.consent, M.env, M.deadline(r))
        if not consent_gate(a_rec, snap.consent).allowed:
            a_rec = SAFE_FALLBACK                           # 同意优先于救命之外的优化
        M.ctrl_out.publish_recovery(a_rec)
        M.cert_ctrl.write(regime=r, primitive=a_rec.id, wcet=M.rtm.wcet_us())
        return a_rec, None, J_RG(M)
    lam = lam_or_switch
    A   = M.ach.propose_ctrl(...); k = M.c_ras_wm.certified_prefix(A, lam, ...)
    M.ctrl_out.publish(k, lam)
    M.last_action = A[:k]
    M.cert_ctrl.write(k=k, lam=lam, regime=r, wcet=M.rtm.wcet_us())

    # ===== 计量域 (50Hz, 软实时) =====
    if M.clock.due_metric():
        reg = M.frr.step(sensors, snap.cap, snap.need.b_n if snap.need else None)
        # regime 切换即让旧证书失效；rupture 时隔离而非降权
        b_post, rupture = quarantine_update(snap.b_prev, obs, reg.r_hat, M.rqm_params)
        need = M.nil.update(M.y_need_buf, M.psi_hat, snap.cap, obs.ctx, M.last_outcome)
        consent = M.consent.update(M.consent_evidence)
        gate = M.r_ivg.check(M.registry, b_post, need, reg, rupture, consent, M.seal.latest)
        if not gate.valid:
            M.mode = gate.fallback
            M.registry.freeze(gate.reason)
        M.snapshot.write(b_post, need, reg, consent, M.psi_hat, M.tac_ev, rupture)

    # ===== 感知域 (Best-effort) =====
    psi_hat, ece_aff = M.aura.update(audio)
    if ece_aff > TAU_AFF: M.psi_hat = None
    tac_ev = M.dmem.update(tac, M.last_action)
    if tac_ev.u_tac > TAU_U_TAC: M.tac_ev = None
    M.y_need_buf.append(extract_need_obs(obs, audio, sensors, M.last_outcome))
    M.consent_evidence.append(extract_consent(obs, audio, M.ctx))
    if M.mode == 'FULL' and reg.r_hat == 'NOMINAL' and need_is_ambiguous(need):
        g = M.rvoi.choose(b_post, need, M.psi_hat, M.budget, M.fmp, M.bse)
        if g:
            y = M.cia.execute(g)                            # 仅在 NOMINAL 允许主动询问
            M.last_g, M.last_y = g, y
    return k, lam, J_RG(M)
```

## 3. 推导

**引理 33（regime 绑定证书的必要性）** 设 J 在 regime r 内有效。若 r' 使证据模型 p_r' 与 p_r 的支撑/矩不一致（如饱和、重尾、时延），则存在一条在 r 内满足风险界的执行，进入 r' 后风险无界（相对 r 的界）。证明：构造 r' 中传感器饱和使 innovation 落在大残差区，而真实状态恰在危险侧；任何仍信任 p_r 的后验都会给出与真实相反的低风险判断。系：**证书没有 regime 标签 = 没有证书。**

**引理 34（λ 天花板与不连通安全集）** 设连续控制族 {π_λ : λ ∈ [λ_floor, λ_max]}，若当前状态 x_t 不在 ∪_{λ≤λ_max} Reach_{T_deadline}(π_λ) 内，而存在恢复原语 a ∈ 𝒜_rec 使 Q_a 满足安全，则任何 λ ≤ λ_max 的连续策略的 T_deadline 内最坏伤害 > H_a^wc，切换 a 严格占优。系：**连续缩放只能「避免」进入不可达区，不能「逃离」不可达区；恢复原语是必要拓扑补丁。**

**引理 35（需求–意图不可识别性）** 若 p(n | z) 非单射，则存在 n₁ ≠ n₂ 与同一意图 z 使 C_need(a(z), n₁) ≪ C_need(a(z), n₂)。故任何仅以 z 为目标的策略，在固定动作下会同时覆盖高伤害需求；仅凭意图证据无法区分。证明：取「拿水」z 对应 n₁=口渴、n₂=噎住；同一动作「递水」对 n₂ 伤害大。系：**需求洞察必须引入能力/语境/后果证据，且其不确定性不可被意图精度消除。**

**引理 36（稀有事件 PPV 下界）** 对检测器 (Se, Sp) 与基率 π，PPV(π) = πSe/[πSe + (1−π)(1−Sp)]。当 π = 10⁻³、Se = Sp = 0.99 时 PPV ≈ 0.090；即使 AUROC = 0.999，在 π = 10⁻⁵ 时 PPV 可低至 <0.01。故**任何不用部署基率下界报告的跌倒检测证书都不构成安全证据**。系：跌倒检测的「准确性」叙事必须换成「在基率下的阳性预测值」。

**引理 37（隔离优于降权）** 设真实模型 p ∈ (1−ε)p_r + εq，q 任意。仅对 p_r 降权（乘以 w<1）时，q 可在 p_r 的支撑内制造任意大的后验锐化；而将 p_r 从锐化路径移除、在 ℬ_safe 上取 minimax 后验，可把最坏伤害限制在保守先验的界内。证明：构造 q 使某危险假设在降权后仍占优；隔离切断了该锐化通道。系：**断裂时「乘个系数」是自我安慰，隔离才是止损。**

**引理 38（恢复选择有限时间终止）** |𝒜_rec| 有限、每个 T_a^wc 有限、且 brace/freeze 永可行，则 minimax 选择在 O(|𝒜_rec|) 内返回；若可行集非空，返回动作的 T^wc ≤ T_deadline；若空，兜底原语保证 H^wc = H_brace^wc < ∞。系：**恢复策略永远有定义、永远在截止时间内给出决策，这是硬实时恢复的可行性前提。**

**引理 39（同意支配）** 对任意 b_t(n)，consent_gate 的输出动作集 A_t ⊆ A_auth。故需求后验再尖锐也不能扩张动作集；同意是比需求更外层的约束。系：**照护系统的安全不是「更准地知道他要什么」，而是「即使知道也不越界」。**

**定理 27（CARE 严格包含与安全单调）** 在 A111–A117（regime 可观测、需求校准有效、跌倒检测基率校正、断裂可检出、恢复原语预认证、同意模型不可伪造、退化链成立）下：CARE 在各退化条件下逐指令等于 EMBODIED/R71/R68（定义 383）；标称 regime 内风险界 ≤ EMBODIED 风险界；断裂后风险界 ≤ H_brace^wc + L_rupt·τ_rupt。**安全单调不减，但需求满足度在保守退化时主动下降。**

**定理 28（J_RG 有效 ⇒ regime 局部安全，且安全依赖 rupture 延迟）** 若一次执行通过 J_RG，则在声明 regime 内、下一次 rupture 前，伤害 ≤ ε_r；若 rupture 已被检出，伤害 ≤ H_brace^wc + L_rupt·τ_rupt，其中 τ_rupt 为断裂检出延迟。**安全证明的重量从「证书是否盖章」转移到「rupture 多快被检出」。**

**定理 29（需求满足的不可保证性）** 在 p(n|z) 非单射且自述有偏的条件下，任何在线策略的需求满足度都存在 minimax 下界：存在两个世界同意图不同需求，使同一策略在一个世界中产生高需要错位伤害。故**我们能保证的是「不因错误需求造成灾难」，不能保证「总满足真实需求」**。这是本框架的诚实边界。

**定理 30（紧迫性攻击的不可完全防御性）** 若攻击者可伪造跌倒信号且检测器必须满足 τ_declare 上界，则存在「假跌倒 → 触发越权/消耗恢复预算」的攻击，使系统在 PPV 与延迟之间两难；完全防御需要**带外第二信道 + 事后审计 + 恢复预算上限**，不能仅靠单通道检测器。系：**紧迫性是新的攻击面，安全系统必须对「被制造的紧急」免疫。**

## 6. 本轮最大风险

**一句话**：CARE-GAUGE-RAS 把安全从「标称工况下的计量审计」推进到「regime 绑定 + 需求洞察 + 同意门控 + 断裂隔离 + 恢复原语」，但它把系统的最终安全性押在三件**本质上不可完全保证**的事情上——**跌倒这种稀有事件的检测在真实基率下仍能有足够 PPV、需求这种隐性变量在分布外仍能被校准且不被社会性伪装击穿、epistemic rupture 能在截止时间内被可靠检出并正确归因**；一旦其中任一失效（例如真实世界跌倒基率远低于标定集、或照护对象系统性隐瞒需求、或 rupture 被高冲击噪声淹没/被攻击者伪造），系统就会在「所有证书都显示有效、所有阈值都显示达标、所有恢复原语都显示已预认证」的情况下，**把人扶成二次伤害、把真实需求漏成事故、把假跌倒当成真紧急去越权**，而事后审计只能看到一条自洽的、盖章的、错误的决策链——这是**照护型具身系统特有的「带着全套合规文件犯下最不可逆错误」**。

# 第 73 轮产物 · 创新点清单 v4：CARE-GAUGE-RAS（Consent-gated, Authentic-need, Recovery-regime, Epistemic-rupture GAUGE for RAS：同意门控 × 真实需求 × 恢复工况 × 断裂隔离的照护型具身计量审计闭环；NIL×FRR×RQM×RPRIM×CONSENT×NHARM×RVOI×GAUGE-RAS††）

> 承接第 72 轮 IP-287~294（EMBODIED-GAUGE-RAS）。R72 完成了「具身层」：REG 实时执行图把「计量不阻塞控制」变成调度级定理；IRL 把意图 z 引入联合后验；DMEM 把灵巧手触觉升级为接触模式条件的计量证据；EREFLEX/ERVOI/E-RISK 把三层反作用合算；S2R-UQ 把 sim2real 残差传播到 WCET 与 λ_floor。R72 的核心姿态是：**「标称工况下，测量链在实时调度里仍能逐指令兑现风险界。」**
>
> 但 R72 有两个未言明的前提，被本轮两个灵感词击穿：
> - **需求洞察（need insight）**：R72 的 z = 「人要我做什么动作」，不是「人真正需要什么」。意图对需求是多对一的；需求隐性、多维、自述有偏、能力依赖、会被失败揭示。R72 可能**正确地执行了错误的需求**，而风险分母漏掉了最大的一项——**需要错位（need misalignment）**。
> - **跌倒恢复（fall recovery）**：R72 的证书是在「站立、协同、传感器不饱和、接触近似高斯」的标称 regime 里证的。跌倒/近跌倒是**稀有、高冲击、传感器饱和、截止时间骤缩、后果不可逆**的尾部事件——不是「更大的噪声」，而是**证书的相变点**；同一个 J_EMB 在跌倒 regime 里可能一字不成立。连续 λ 缩放也救不了「安全集与当前状态不连通」。
>
> 本轮把「具身计量审计」推进到 **CARE-GAUGE-RAS**：**工况绑定、需求洞察、同意门控、断裂隔离、恢复优先的照护型计量审计闭环**。
>
> 核心命题：**不再只问「标称工况下测量链可信吗」，而问「当人真正需要的与嘴上说的不一致、当系统/人正在跌倒、当旧模型瞬间失效时，系统能否先停住、再救、最后才谈优化？」**
>
> 五个关键转向：
> 1. **intent → need**：区分 b_t(z) 与 b_t(n)；需求证据含自述/行为/能力/语境/后果；需求校准、需要错位代价、自主性代价；需求不确定度进入**伤害**。
> 2. **频率分离 → regime 分离**：r ∈ {NOMINAL, ATTENTIVE, CRITICAL, RECOVERY, POST}；证书/后验必须带 regime 标签与有效性包络 D_r；跨 regime 即失效。
> 3. **降权 → 隔离（quarantine）**：epistemic rupture 时把旧后验隔离、退回保守先验，而不是「把旧似然乘个系数」。
> 4. **连续缩放 → 离散逃逸**：λ 有天花板；连续安全集不可达时，切换到预认证恢复原语，用 minimax 而非期望。
> 5. **绩效 → 同意**：同意是硬约束，不是代价项；需求再大也不能越过「明确拒绝 / 预立医嘱」。
>
> IP 编号：IP-295~302（共 8 个）+ EMBODIED 组件的 †† 化。理论姿态延续：**新层是旧层的严格泛化，安全侧只增不减，需求满足度可在保守退化时主动下降。**

## 2. 形式化定义（要点版）

**定义 366（总览与六不变式）** CARE = (NIL, FRR, RQM, RPRIM, CONSENT, NHARM, RVOI, GAUGE-RAS††)。六不变式：(i) regime 绑定有效性；(ii) need–intent 分离；(iii) 同意优先（A_t ⊆ A_auth）；(iv) 恢复字典序优先（最坏伤害 → 到安全态时间 → 需求 → 信息）；(v) 断裂隔离（越界即 quarantine，不降权）；(vi) 严格退化链 CARE ⇒ EMBODIED ⇒ GAUGE ⇒ R68。

**定义 367（潜在需求模型）** n 五维、部分有序；硬需求 𝒩_hard（人身安全、同意），软需求 𝒩_soft（舒适、效率、社交、自主）。b_t(n)=p(n|ℋ_t,cap_t,x_t)；需求转移 p(n'|n,a,o)。**p(n|z) 一般非单射 ⇒ 仅意图不可识别需求。**

**定义 368（需求证据与代价敏感校准）** y_need = (自述, 行为生理, 语境, 上一步后果)；p_need = Σ_k ω_k(ψ,x)·p_k(y_need|n,z)。输出 (n̂,b_t(n),ECE_need,cov_hard,ι_need,FNR_need(π),FPR_help(π),autonomy_cost)。**基率与子人群必须显式报告；漏硬需求与过度帮助都计伤害。**

**定义 369（regime 状态机）** r ∈ {NOMINAL, ATTENTIVE, CRITICAL, RECOVERY, POST}；转移 p(r'|r,s,fall_risk,a) 带守卫。**regime 有后验 b_t(r)；证书仅在 r̂ = r_cert 且 b_t(r_cert) ≥ 1−ε_r 时有效。**

**定义 370（跌倒检测的基率校正证书）** 序贯检验（SPRT/CUSUM）输出 (Se,Sp,E[τ_detect],τ_declare,α,β)。部署证书必须给 PPV(π_L) 且只在 PPV(π_L) ≥ τ_ppv 时宣告；近跌倒独立标签。**AUROC 不是安全证据。**

**定义 371（regime 条件计量与断裂）** p_r(y|s,c) 随 r 变；innovation e_t=y_t−h_r(ŝ_t)，断裂统计量 R_t = eᵀΣ_r⁻¹e + M_s·1[saturated] + M_t·1[sync>τ] + M_i·1[impulse>I_max]。R_t > κ_r 或硬指标越界 ⇒ **epistemic rupture**：p_r 不再可用。

**定义 372（隔离滤波器 Q-filter）** 断裂时 b_t^Q ∈ argmin_{b∈ℬ_safe} max_{p∈𝒫_r} E_b[ℓ(s,a)]；非断裂时正常贝叶斯。**隔离移除旧模型的锐化通道，降权只缩小其权重。**

**定义 373（恢复原语库）** 𝒜_rec 预认证：brace/compliant-collapse/roll/push-up/kneel/crawl/freeze/call-help/light-assist/full-assist；每个带 (P_a, T_a^wc, H_a^wc, Q_a, auth_a, F_a^wc)。**在线只选，不现场发明。**

**定义 374（截止时间 minimax 恢复）** π_rec = argmin (H_a^wc, T_a^wc)（字典序）s.t. T_a^wc ≤ T_deadline、P_a 高概率成立、auth_a 成立；可行集空 ⇒ brace/freeze 兜底。**恢复不做期望最优：期望依赖的模型正是被断裂摧毁的那个。**

**定义 375（R-VoI 与信息负债）** RVoI(g)=(ΔH_harm,ΔT_safe,ΔH_need)，字典序比较。信息动作仅当不消耗恢复截止时间且最坏伤害不劣于无信息时允许；认知预算 B_epi(r) 随紧迫度收缩。

**定义 376（需求感知伤害与 λ 饱和）** H = H_safe + α·H_need-misalign + β·H_autonomy + γ·H_trust；λ 增 λ_need(H[b(n)],p(f)) 与 λ_consent，但设 λ_max。**若 x_t 不在 ∪_{λ≤λ_max} Reach_{T_deadline}(π_λ) 内，则必须切 𝒜_rec。**

**定义 377（同意/授权）** a ∈ {yes,no,directive,emergency-presumed,unknown}。`no/directive` 否决 >F_light 的干预；`unknown` 仅最小侵入；`emergency-presumed` 仅当「不干预最坏伤害严格更大」且事后审计。**同意是不确定性的硬上限，不能被需求后验抵消。**

**定义 378（失败揭示需求与断裂归因）** p(n,θ|f=1) ∝ p(f=1|n,θ)p(n,θ)；允许有界结构更新（新需求类别/风险模型），但结构更新须离线复核后才能驱动高力动作；归因默认 unknown → 保守。

**定义 379（R-MIB）** 需求族（ECE_need/FNR_need/FPR_help/cov_hard/需要错位代价/自主性代价/ι_need）、跌倒族（Se/Sp/PPV(π_L)/τ_detect/τ_declare/近跌倒召回/误报负担）、恢复族（T_safe/H^wc/恢复成功率/再跌倒率/原语覆盖/二次伤害率）、regime 族（失配率/证书失效率/τ_rupt/复证时间）、同意族（硬否决正确率/越权率/紧急假定审计）、信任族（自报校准/过度声称/信任余额）。

**定义 380（R-IVG）** 新增失效：需求（ECE/FNR/cov/H(n)/ι 超阈）、跌倒（PPV/延迟/误报超阈）、regime（失配/rupture 未检出）、恢复（无可行授权原语/H^wc 超预算/deadline 不可满足）、同意（需高力且 unknown/no）。任一成立 ⇒ 对应模块降级。

**定义 381（CARE 证书 J_RG）** Valid ⇔ J_EMB 有效 ∧ regime 匹配且 b_t(r) ≥ 1−ε_r ∧ PPV 界成立 ∧ 需求校准有效 ∧ 同意校验通过 ∧ 恢复计划在 deadline 内且已授权。

**定义 382（威胁模型 AIC-REC）** ℰ_REC = ℰ_EMB × ℰ_regime × ℰ_need × ℰ_fall × ℰ_consent。新增：regime 混淆/证书重放/rupture 洪水（拒绝服务）；需求隐瞒伪装/对抗诱导/文化误读；跌倒检测欺骗规避/假跌倒诱发越权；同意伪造/医嘱篡改/紧急假定滥用。**本质：攻击者可操纵「紧迫性」绕过审慎。**

**定义 383（严格退化链）** 全有效 ⇒ CARE；NIL 失效 ⇒ 显式意图 + R72；regime/FRR 失效 ⇒ 保守后验 + brace/freeze；同意不足且需高力 ⇒ 仅 call-help/light-assist；全失效 ⇒ R68。**安全单调不减；需求满足度在退化时主动下降。**

**定义 384（信任修复与恢复报告）** 恢复后产出校准报告（发生了什么/各判断置信/哪些模型更新/残余风险/如何避免），禁止过度声称；信任负债 D_trust = 过度声称 − 实际可靠性，超阈触发更保守交互。

```python
class NeedInsightLayer:
    def __init__(self, need_net, calib, cost_matrix):
        self.net, self.calib, self.C = need_net, calib, cost_matrix

class FallRecoveryRegime:
    def __init__(self, hazard, sprt, hmm, tau_ppv, tau_declare):

        self.tau_ppv, self.tau_declare = tau_ppv, tau_declare
    def step(self, sensors, cap, b_n):

        self.sprt.update(sensors.fall_evidence)

        r_post = self.hmm.step(sensors, fall_risk, declared)
        r_hat  = argmax_regime(r_post, hysteresis=H_R)          # 防 regime 抖动

# IP-297 RQM：断裂隔离滤波器（控制域 1kHz）
def quarantine_update(b_prev, y, r, params):
    e  = innovation(y, r)
    Rt = e @ inv(params.Sigma_r) @ e
    rupture = (Rt > params.kappa_r) or saturated(y) or (params.sync_err > params.tau_sync)
    if rupture:
        return minimax_safe_posterior(b_prev, params.mathcal_P), RuptureFlag(True, Rt)
    return bayes_update(b_prev, likelihood_r(y, r)), RuptureFlag(False, Rt)

             and a.T_wc <= T_deadline]

# IP-299 RVOI：恢复期价值（字典序；信息是负债）
def recovery_voi(g, deadline, B_epi, b_n):

    return (g.delta_harm, g.delta_T_safe, g.delta_need)

# IP-300 NHARM：需求感知伤害 + λ 饱和切恢复
def care_risk(U_ale, U_epi, H_z, u_tac, H_n, p_fall, consent_unc, params):
    denom = U_ale + U_epi + H_z + u_tac.total()
    lam = max(params.lam_base * (1 + denom / params.lam_scale),
              params.lam_floor * (1 + denom),
              params.lam_need * (1 + H_n + p_fall),
              params.lam_consent * (1 + consent_unc))
    lam = min(lam, params.lam_max)
    if lam >= params.lam_max or not continuous_safe_reachable(lam, params.T_deadline):
        return SWITCH_RECOVERY
    return lam
```

## 4. 推导

**引理 33（regime 绑定证书的必要性）** 若 p_r' 与 p_r 的支撑/矩不一致（饱和、重尾、时延），则存在一条在 r 内满足风险界的执行，进入 r' 后风险无界（相对 r 的界）。系：**证书没有 regime 标签 = 没有证书。**

**引理 34（λ 天花板与不连通安全集）** 若 x_t ∉ ∪_{λ≤λ_max} Reach_{T_deadline}(π_λ)，而存在 a∈𝒜_rec 使 Q_a 安全，则任何 λ≤λ_max 的连续策略的 T_deadline 内最坏伤害 > H_a^wc，切换 a 严格占优。系：**连续缩放只能「避免」进入不可达区，不能「逃离」不可达区。**

**引理 35（需求–意图不可识别性）** 若 p(n|z) 非单射，则存在 n₁≠n₂ 与同一 z 使 C_need(a(z),n₁) ≪ C_need(a(z),n₂)；任何仅以 z 为目标的策略在同一动作下会覆盖高伤害需求。系：**需求洞察必须引入能力/语境/后果证据，且其不确定性不可被意图精度消除。**

**引理 36（稀有事件 PPV 下界）** PPV(π)=πSe/[πSe+(1−π)(1−Sp)]。π=10⁻³、Se=Sp=0.99 ⇒ PPV≈0.090；π=10⁻⁵ 时 PPV 可 <0.01。故**不用部署基率下界报告的跌倒检测证书不构成安全证据**。

**引理 37（隔离优于降权）** 设真实 p ∈ (1−ε)p_r + εq，q 任意。对 p_r 降权（×w<1）时，q 可在 p_r 支撑内制造任意后验锐化；将 p_r 移出锐化路径、在 ℬ_safe 上取 minimax 后验，可把最坏伤害限制在保守先验界内。系：**断裂时「乘个系数」是自我安慰，隔离才是止损。**

**引理 38（恢复选择有限时间终止）** |𝒜_rec| 有限、T_a^wc 有限、brace/freeze 永可行 ⇒ minimax 选择 O(|𝒜_rec|) 返回；可行集非空则 T^wc ≤ T_deadline；空则 H^wc = H_brace^wc < ∞。

**引理 39（同意支配）** 对任意 b_t(n)，consent_gate 输出 A_t ⊆ A_auth；需求后验再尖锐也不能扩张动作集。系：**照护系统的安全不是「更准地知道他要什么」，而是「即使知道也不越界」。**

**定理 27（严格包含与安全单调）** 在 A111–A117 下：CARE 在退化条件下逐指令等于 EMBODIED/R71/R68（定义 383）；标称 regime 内风险界 ≤ EMBODIED 风险界；断裂后风险界 ≤ H_brace^wc + L_rupt·τ_rupt。**安全单调不减，需求满足度在保守退化时主动下降。**

**定理 28（J_RG 有效 ⇒ regime 局部安全，且安全依赖 rupture 延迟）** 通过 J_RG ⇒ 声明 regime 内、下一次 rupture 前伤害 ≤ ε_r；rupture 已检出时伤害 ≤ H_brace^wc + L_rupt·τ_rupt。**安全证明的重量从「证书是否盖章」转移到「rupture 多快被检出」。**

**定理 29（需求满足的不可保证性）** 在 p(n|z) 非单射且自述有偏下，任何在线策略的需求满足度存在 minimax 下界：存在两个世界，同意图不同需求，使同一策略在一个世界中产生高需要错位伤害。**我们能保证「不因错误需求造成灾难」，不能保证「总满足真实需求」——这是诚实边界。**

**定理 30（紧迫性攻击的不可完全防御性）** 若攻击者可伪造跌倒信号且检测器须满足 τ_declare 上界，则存在「假跌倒 → 触发越权/耗尽恢复预算」的攻击；完全防御需**带外第二信道 + 事后审计 + 恢复预算上限**，不能仅靠单通道检测器。

### 6.1 解析算例（非实验数据，仅说明基率陷阱）

设部署基率 π = 10⁻³，检测器 Se = Sp = 0.99。则每 10 万人中：真实跌倒 100 人，检出 99；非跌倒 99900 人，误报 999。PPV = 99/(99+999) ≈ 9.0%。即**每 10 个报警只有不到 1 个是真的**。把同一检测器搬到 π = 10⁻⁵ 的场景，PPV ≈ 0.1%。这解释了为何 E371 必须用 PPV(π_L) 而非 AUROC 作为部署门槛，也解释了为何定义 370 要求「近跌倒独立标签」——提高先验的有效方式是识别前驱事件，而不是提高单帧分类精度。

## 7. 本轮最大风险

**一句话**：CARE-GAUGE-RAS 把安全从「标称工况下的计量审计」推进到「regime 绑定 + 需求洞察 + 同意门控 + 断裂隔离 + 恢复原语」，但它把最终安全性押在三件**本质上不可完全保证**的事上——**跌倒这种稀有事件在真实基率下仍有足够 PPV、需求这种隐性变量在分布外仍能被校准且不被社会性伪装击穿、epistemic rupture 能在截止时间内可靠检出并正确归因**；一旦任一失效（真实跌倒基率远低于标定集、照护对象系统性隐瞒需求、rupture 被高冲击噪声淹没或被攻击者伪造），系统就会在「所有证书显示有效、所有阈值显示达标、所有原语显示已预认证」的情况下**把人扶成二次伤害、把真实需求漏成事故、把假跌倒当成真紧急去越权**，而事后审计只能看到一条自洽、盖章、错误的决策链——这是**照护型具身系统特有的「带着全套合规文件犯下最不可逆错误」**。

次级风险与缓解：
1. **稀有事件基率漂移** → 部署期用**分层基率下界 π_L + 前驱近跌倒**重估 PPV；PPV 不达标即**禁止自动宣告**，退回「提示+人工确认」。
2. **需求自述偏差/文化差异** → **SEAL-Need 密封审计集**（跨文化/失能/隐忍场景）；自述权重 ω_self(ψ,x) 由 ψ 与语境调制；硬需求走**多通道一致性**，单源不判硬需求。
3. **rupture 漏检/误检** → **双通道断裂检测**（统计 innovation + 语义/物理合理性）；rupture 洪水攻击用**冷却窗口 + 恢复预算上限**；假 rupture 不重置安全约束。
4. **恢复原语未覆盖场景** → **永久可行的 brace/freeze 兜底** + 离线原语库扩展流程；未知场景 E392 作为发布门槛。
5. **同意模型被伪造/紧急假定滥用** → 同意走**带外第二信道 + 防篡改日志**；emergency-presumed 需**事后审计 + 不可否认记录**；任何高力动作都有硬否决。
6. **需求结构更新污染安全约束** → 在线只允许参数收缩；结构更新（新需求类别/改安全约束）**离线复证后才能用于高力动作**（定义 378）。
7. **复杂度爆炸** → **模块化上限**：|n|≤8 维、|ℛ|≤5、|𝒜_rec|≤12、|𝒜_auth|≤5；每个 veto 一条可复算证明；需求/跌倒/恢复/regime/同意五族指标全部纳入审计。
