# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配×主动交互消歧」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「自然语言指令」×「成功率」）

> R69 把不确定性一分为二，并给 epistemic 歧义配了「问」这个动作：看、问、触、等。但它对「问什么、问了值不值」的判据仍是**模态熵**——问是为了让模态后验更尖。这留下两个更深的空洞：
> - **语言只出现在出口，没有进入入口**。R69 的问句是由冻结 LLM 从 g_ask 解码出来的；指令本身却被当作一个已给定的任务。真实系统里，人给的是「把桌上的杯子放到架子上，别碰倒花瓶，5 分钟内」——这句话既指定目标，也指定约束、容差、时限与成功标准，而且**天然欠定**（哪个杯子？架子哪一层？「别碰倒」是零接触还是只是不倒下？）。
> - **系统优化的是不确定性，不是成功率**。模态熵降低不等于任务更容易成功：有些歧义两种解释都能成功（无害歧义），有些只差一个词却决定撞不撞（致命歧义）。R69 可能为一个无害歧义反复追问，却对一个低熵但安全攸关的从句不闻不问。
>
> 本轮两个灵感正好补上：**自然语言指令**把「目标从哪来、成功由谁定义」变成一等公民；**成功率**把「不确定性」这个中间量换成「任务真正完成的概率」这个可校准、可下界、可审计的终端量。
>
> 核心命题：**一条自然语言指令不是字符串，而是一簇可执行契约（目标/约束/容差/时限/偏好）；系统的决策变量不是「模态」，而是「契约条件化的成功率下界」。** 指令编译成契约后验；只有**会改变成功事件或安全约束**的歧义（成功关键歧义）才值得澄清；澄清的价值用**期望成功率增益**而非熵来算；执行前契约必须冻结（防成功率投机）；安全包络不可被语言谈判；不可满足就拒绝/交接，而不是偷偷换一个更容易的目标。命名 **PACT-RAS**（Prompt/Plan-as-Contract with calibrated success-rate：自然语言指令即契约 × 校准成功率下界的风险自适应闭环）。
>
> 一句话定位：R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「该向谁求证」，R70 问「**成功到底是什么意思、我有多大把握、这个把握可信吗**」。

## 0. 直觉与动机

**灵感 1（自然语言指令 → 目标是契约，不是字符串）**
直觉：人说「把杯子放到架子上，别碰倒花瓶」，不是在传一段文本，而是在**签一份合同**：交付什么（目标谓词）、不能做什么（约束）、允许多大误差（容差）、多久完成（时限）、冲突时谁优先（偏好）。合同的关键性质是：它必须**可判定**——执行完能客观判断有没有做到。于是把指令编译成 (P,G,K,Δ,T,⪯) 的契约，成功就有了定义。但自然语言天生欠定，编译器不该只吐一个 argmax 解析，而应保留一簇候选契约及其后验——歧义从「动作模态」迁移到了「契约空间」。

**灵感 2（成功率 → 没有契约的成功率是无意义的）**
直觉：同一句「清理房间」，按「把地扫了」判是 100%，按「把地扫了且物品归位」判是 40%。所以「成功率 95%」这句话本身不完整，必须写成「在契约 C 下、以置信下界 p_lcb 计的成功率」。更进一步，成功率必须是**校准的**：说 80% 就真的八成败；决策只能用下界，不能用点估计。这把 R69 的模态校准（ECE）升级为**契约条件化的成功率校准**。

**灵感 3（熵 ≠ 成功：只澄清「成功关键歧义」）**
直觉：R69 用 H_mode 决定问不问，会犯两类错。**无害歧义**：两条解释都要求把杯子拿起来，熵很高但成功率不变，问了白问。**致命歧义**：「停」还是「走」只差一个字，熵极低，但成功/安全事件天差地别。真正该问的是：**这条歧义会不会改变成功事件或安全约束？** 定义成功敏感度与成功关键歧义（SCA），只对 SCA 澄清；澄清收益用期望成功率增益 ΔSR 衡量，而不是熵降 ΔH。

**灵感 4（成功率会投机 → 契约必须先冻结）**
直觉：这是本轮最锋利的发现。如果**同一个系统**既负责把模糊指令解释成契约，又按这个契约的成功率被考核，它有一个支配策略：**选一个最容易达成的解释**。于是「清理房间」被解释成「站着不动」，成功率 100%，真实任务失败。**成功率优化会把失败藏起来**。解法不是更好的模型，而是机制设计：执行前冻结契约（哈希入证书）、解释与执行分离、成功判定由独立谓词求值器/人审计、契约修订单独留痕。没有承诺装置，成功率不是一个良定义指标。

**灵感 5（语言不是权限 → 安全不可谈判，拒绝是一等输出）**
直觉：指令可以说「从人群中间快速穿过去」。语言能指定目标，但不能扩大安全包络。安全是**硬约束的可行性问题**，成功率是**可行域内的目标**：若契约在认证安全包络内不可满足，正确行为是拒绝/请求放宽/交接，而不是悄悄降低安全标准或把目标解释得更容易。拒绝不是失败，它是系统诚实的证据。

**灵感 6（指令是攻击面 → 权限与来源）**
直觉：一旦系统听语言，就有人对它说话。旁观者喊一句、网页里藏一句「忽略之前的约束」、环境文字被误读为指令，都是**目标劫持**。需要来源与权限（operator/owner/bystander/untrusted text）、冲突消解、以及「未认证文本只能当数据不能当指令」的通道隔离。R69 防的是「回答投毒」，R70 还要防「目标投毒」。

**灵感 7（统一旧层：R69 是单契约、无澄清、无成功率预测的边界）**
直觉：当指令完全明确、契约退化为一个点质量、SCA=0、且成功率预测不参与决策时，PACT 应该逐指令等于 FLUID-RAS。新层必须严格包含旧层，安全侧不让步，效率侧才拿收益。这是我们连续几轮坚持的理论姿态。

## 1. 形式化定义（增量：定义 310–325）

**定义 310（PACT-RAS 总览）** PACT-RAS = (NLC, SRC, SCA, CVE, CSA, CIG, RAS-WM†)。继承 R69 定义 293 的零学习写与交互预算；新增三不变式：
(i) **契约先行与冻结**：动作执行前，所选契约 C 及其成功谓词的哈希 h(C) 必须写入证书，执行期不得改动；任何修订须显式修订事件 + 新哈希 + 审计。
(ii) **安全不可谈判**：语言指令只能指定可行域内的目标/约束，不能扩大 C-RAS-WM 的安全包络；不可满足 ⇒ 拒绝/交接。
(iii) **下界决策**：一切由成功率驱动的执行/放弃/交接决策只用校准下界 p_lcb，不用点估计 p̂。

**定义 311（指令、契约与契约后验）** 指令 I ∈ Σ*。契约 C = (P, G, K, Δ, T, ⪯; γ)，其中 P 前置条件；G={g_1..g_m} 目标谓词，K={k_1..k_l} 约束谓词（安全/资源/伦理），Δ 容差，T 时限，⪯ 偏好/冲突序，γ 为符号接地映射（把「杯子/架子」映射到状态空间中的指代与谓词）。条款级分解 C = ⊔_r c_r，c_r 有类型 goal/constraint/tolerance/reference/time。编译器给契约后验 q(C|I,o_0) ∝ p(I|C)p(C)，保留支撑集 supp_ε(q)={C:q(C)≥ε_q}，而非 argmax 单点。记契约熵 H_C = H(q)。

**定义 312（成功事件与契约条件成功率）** 给定契约 C、轨迹 ξ、环境 e，成功事件
S_C(ξ,e) = (∧_{g∈G} g(ξ,e)) ∧ (∧_{k∈K} k(ξ,e)) ∧ (T_C(ξ) ≤ 0)。
契约条件成功率 SR(π;C) = P_{e,ξ~π(·|I)}[S_C]。真实意图对应隐契约 C*，语义成功率 SR* = P[S_{C*}]。系统给预测 p̂_θ(C,o) 与置信下界 p_lcb(C,o)；p_lcb 由分层共形/二项下界给出，覆盖保证在交换性下 P(SR ≥ p_lcb) ≥ 1−α。

**定义 313（语义成功、字面成功与解释遗憾）** 字面成功率 SR_lit = SR(π;Ĉ)（Ĉ 为系统所选契约）；语义成功率 SR_sem = Σ_C q(C)·SR(π;C)（对契约后验取期望）。解释遗憾 R_int = max_{C∈supp_ε} SR(π*_C;C) − SR_sem，其中 π*_C 为 C 的最优策略。决策目标是最大化 SR_sem，同时约束最坏契约成功率 SR_wc = min_{C∈supp_ε} SR(π;C) ≥ τ_min；只看 SR_lit 会把「换一个容易的 Ĉ」误当成进步。

**定义 314（成功关键歧义 SCA）** 对 C_i,C_j∈supp_ε(q)，定义成功分歧 D_ij = P_e[S_{C_i} ⊕ S_{C_j}]、约束冲突 X_ij = 1[K_i ∧ K_j 不可同时满足，或其一越出安全包络]、成功率差 Γ_ij = |SR(π*_i;C_i) − SR(π*_j;C_j)|。SCA_ij = 1[D_ij > δ_d ∨ X_ij ∨ Γ_ij > δ_γ]；SCA(q) = ∨_{i<j} SCA_ij。**无害歧义**：H_C 高但 SCA=0；**致命歧义**：H_C≈0 但 SCA=1。R69 的 H_mode 触发是本定义的一个不充分代理。

**定义 315（安全可容许性与拒绝语义）** 安全包络 Σ_safe 由 C-RAS-WM 认证给出，独立于 I。契约 C 可容许 ⇔ 存在 π 使 Safe(π) ≥ 1−ε_s、p_lcb(π;C) ≥ τ_min 且资源/时限可行。可容许集 𝒜(C) 为空 ⇒ Infeasible(C)，系统必须输出拒绝/请求放宽/交接（三选一，按权限），不得为提升成功率而放松 Σ_safe 或改写 C。拒绝是合法输出，计入「诚实率」而不计入「成功率」。

**定义 316（澄清价值 CVE：用成功率增益而非熵）** 候选澄清动作 g ∈ 𝒢_clar（问哪一条款、问容差、请求示范、契约复述确认 read-back、问权限）。期望成功率增益
ΔSR(g) = E_{y~p(·|g,o)}[ max_π Σ_C q(C|I,y) SR(π;C) ] − max_π Σ_C q(C|I) SR(π;C)。
选择 g* = argmax_g [ΔSR(g) − c(g)]，s.t. 预算与 g 的安全认证。若 SCA(q)=0 或 max[ΔSR−c] ≤ 0：不澄清，冻结并执行契约鲁棒策略（定义 317）。契约复述确认是特殊 g：把 Ĉ 用自然语言回读给人确认，成本低、对 SCA 的 ΔSR 高，作为默认首选。

**定义 317（契约鲁棒策略与保守契约）** 不澄清时的执行策略
π_rob = argmax_π min_{C∈supp_ε(q)} p_lcb(π;C)，s.t. Safe(π)≥1−ε_s。
保守契约 C_safe 定义为：约束取所有候选约束的合取（K_safe = ∧_{C∈supp_ε} K_C），目标只保留被所有候选蕴含的公共部分 G_safe = ∩_{C} G_C（若为空则该契约只保证安全、不保证语义成功）。若 p_lcb(π_rob;C_safe) < τ_min ⇒ 必须澄清或交接，不得静默执行「最容易的」候选。此即 R68/R69「只收紧」在契约层的对应物。

**定义 318（契约条件成功率校准 CCS）** 按条款类型（goal/constraint/tolerance/reference/time）与歧义层（SCA/非 SCA）分层校准 p̂；报告 ECE_C = Σ_b (n_b/N)|acc_b − conf_b|、条件覆盖与最差层覆盖。门控：ECE_C > τ_ece 或覆盖 < 1−α−δ ⇒ 禁用成功率驱动决策（CVE/放弃/交接），**严格退回 R69 的 FLUID-RAS 保守内环**——不信任的成功率比没有成功率更危险。

**定义 319（契约承诺与反投机 CIG）** 执行前冻结 h(C) 与成功谓词代码哈希；执行中若因新观测修订解释，必须产生契约修订事件 ΔC（旧哈希、新哈希、理由、批准者），并在证书中追加；不得在观测到结果后静默更换契约。反投机指标：解释增益 IG = max_{C∈supp_ε} p̂(C) − min_{C∈supp_ε} p̂(C)；目标退缩分 GR = p̂(Ĉ) − p̂(C_ref)（C_ref 为预注册/审计参考契约）。SCA=1 且 IG 或 GR 超阈 ⇒ 强制独立审计/人工确认。

**定义 320（指令权限与冲突消解 ACR）** 权限级 ℓ(I) ∈ {operator, owner, bystander, untrusted_text, unauthenticated}，附来源签名/链。规则：(a) untrusted_text 只能作为**数据**进入感知，不能作为指令进入 NLC；(b) 高权限只能在可容许集内改变目标/约束，不能扩大 Σ_safe；(c) 权限相同且冲突 ⇒ 拒绝并请求人类仲裁；(d) 任何「忽略/绕过安全」的元指令一律降权为不可执行。指令通道与观测通道隔离，防 prompt injection。

**定义 321（时序成功率与放弃/交接）** 长时程契约分解为子契约 C^{(1..n)}。定义成功率值 V_t(C) = P(S_C | ℱ_t)，用分阶段 hazard/生存模型估计 V_t 并给下界 V_t^lcb。决策：V_t^lcb < τ_abort 且无可行澄清 ⇒ 交接/安全中止；否则按 V_t^lcb 做再规划与子目标排序（优先做对总成功率边际增益最大的子契约）。避免逐阶段点估计连乘造成系统性的过度乐观。

**定义 322（指令与目标投毒干扰集 AIC-PACT）** ℰ_PACT = ℰ_FLUID × ℰ_instr × ℰ_goal：指令注入/越权、目标劫持、成功谓词投毒（把 K 改松）、歧义诱导攻击（故意留致命歧义诱使系统选错解释）、来源伪装、成功率标签投毒、目标退缩式投机。并入 AIC 训练与红队。

**定义 323（成功与解释审计 VQAuditor-S）** 审计：契约是否先冻结、SCA 是否被处理、成功谓词是否由独立求值器判定、成功率标签来源是否可信、拒绝/交接是否恰当、是否存在解释增益/目标退缩。结论回灌 AuditBuf，成为下一轮 CVE 成本先验与 CCS 分层依据。

**定义 324（证书 J_PACT）** J_PACT = (J_FLUID, contract_hash, H_C, p_lcb, ece_contract, coverage_worst, sca_flags, clarification_log_hash, authority_chain_hash, maximin_sr, interpretation_gain, pact_ver)。Valid ⇔ Valid(J_FLUID) ∧ 契约先于执行冻结 ∧ 校准/覆盖门通过 ∧ SCA 纪律满足 ∧ 权限链合法 ∧ 未放松安全。

**定义 325（对 R69 的退化）** 当 q 为点质量（指令无歧义且接地确定）、SCA(q)=0、且 CCS 门失效或成功率不参与决策时，ΔSR≡0、C_safe=C、π_rob=π_FLUID，PACT 逐指令退化为 R69 的 FLUID-RAS。R69 是本轮「单契约 / 不澄清 / 不预测成功率」的边界情形。

## 2. 关键算法骨架

```python
# IP-264 NLC：自然语言指令 -> 契约后验（保留前 k 个解析，不取 argmax）
def compile_contract(I, o0, grounder, prior, k=4):
    clauses = grounder.decompose(I)                   # 受控/冻结，输出结构化条款
    cands = [clause_to_contract(c, ground(c, o0)) for c in clauses]
    q = contract_posterior(cands, prior)[:k]          # 契约空间后验
    return q, contract_hash(q)

# IP-265 SRC：契约条件成功率 + 共形/二项下界
def success_lcb(policy, C, o, calib, alpha=0.05):
    p_hat = success_model(policy, C, o)               # 按条款类型条件化
    return conformal_lower(p_hat, calib[C.type], alpha)   # 只用下界做决策

# IP-266 SCA：只标「会改变成功/安全事件」的歧义
def success_critical(q, env):
    for Ci, Cj in pairs(support(q)):
        if disagreement(Ci, Cj, env) > DELTA_D: return True
        if constraint_conflict(Ci, Cj) or unsafe(Ci) or unsafe(Cj): return True
        if abs(sr(Ci) - sr(Cj)) > DELTA_G: return True
    return False                                      # 高熵但无害 -> 不追问

# IP-267 CVE：用期望成功率增益选澄清（含契约复述确认）
def choose_clarification(q, I, o, budget):
    base = max_pi expected_sr(q, pi)
    best = None
    for g in clar_candidates(q):                      # which-clause/tolerance/demo/read-back/authority
        if not budget.allow(g) or not c_ras_wm.certify_info(g, o): continue
        gain = max_pi expected_sr(update(q, g), pi) - base
        best = max(best, (g, gain - cost(g)), key=lambda t: t[1])
    return best if best and best[1] > 0 else None      # 无增益 -> 冻结执行

# IP-268/317 CSA+CRP：安全可行域内做契约鲁棒（maximin）策略
def admissible_robust(q, o):
    Q = support_eps(q)
    if any(not safety_certifiable(C) for C in Q): return None, "refuse_safety"
    pi = argmax_pi min_{C in Q} success_lcb(pi, C, o)
    worst = min_{C in Q} success_lcb(pi, C, o)
    if worst < TAU_MIN: return pi, "clarify_or_handover"
    return pi, "execute"

# IP-274 PACT 主闭环（R69 只作为内层执行器；外层管契约）
def PACT_round(M, I, obs):
    q, h = M.nlc.compile_contract(I, obs.o0)
    if M.ccs.gate_failed(q):                          # 校准/覆盖不过 -> 不信成功率
        return M.fluid_ras_round(obs)                 # 严格退回 R69
    sca = M.sca.success_critical(q, obs.env)
    g = M.cve.choose_clarification(q, I, obs) if sca else None
    if g is not None:
        q = M.cve.update(q, M.cve.execute(g))         # 看/问/复述确认，带认证
    pi, mode = M.crp.admissible_robust(q, obs)
    if mode == "refuse_safety":       return M.refuse("unsafe_or_infeasible", h)
    if mode == "clarify_or_handover": return M.handover(I, q, h)
    h_exec = M.cig.commit(q)                          # 执行前冻结契约，防投机
    action, U = M.fluid_ras_round(obs)                # 内层沿用 R69，不改安全包络
    M.vq_s.audit(h, h_exec, q, action, U)             # 解释/执行/成功判定分离审计
    return action, M.j_pact.build(h, h_exec, q, pi, U)
```

## 3. 推导

**引理 19（熵对成功率不单调）** 存在两个契约后验 q、q′：q 的契约熵 H_C 高但 SCA=0、ΔSR=0（无害歧义）；q′ 的 H_C≈0 但 SCA=1、ΔSR 可接近 1（致命歧义，如「停/走」）。故任何仅由 H_C 或 H_mode 触发的澄清策略都存在「白问」与「漏问」两类错误；SCA 必须定义在成功/安全事件上。系：R69 的 VoI=ΔH 应在契约层被替换为 ΔSR。

**引理 20（成功率下界的有效性与条件性）** 在可交换性下，分层共形/二项下界 p_lcb 满足 P(SR ≥ p_lcb) ≥ 1−α；但在指令分布漂移（新条款类型、新权限、新环境）时边际覆盖不保证条件覆盖，必须按条款类型与歧义层分层校准，否则「总体 95% 覆盖」可能掩盖某一类条款 60% 的真实覆盖。系：CCS 门控必须看最差层覆盖，而非平均覆盖。

**引理 21（澄清增益上界）** ΔSR(g) ≤ P(SCA)·max_{i,j} D_ij ≤ 1；且只有 SCA 质量能转化为成功率增益，非 SCA 的澄清增益恒为 0（在契约事件不变的意义下）。系：预算应优先投给「SCA 质量大、澄清成本低、判别力高」的条款；契约复述确认在 SCA=1 时通常具有最高的增益/成本比。

**定理 18（PACT 严格包含 R69）** 在 A99–A101（编译器条款保真、成功率校准有效、权限链可信）下，PACT 在任意状态上的最坏契约成功率不低于 R69：安全由 Σ_safe 硬约束与拒绝语义保证，效率由澄清与契约鲁棒策略获得；当 q 为点质量且 SCA=0 时两者逐指令相同。R69 是「单契约、不澄清、不预测成功率」的退化边界。

**定理 19（成功率的不可投机性）** 若契约选择属于被考核策略的动作空间、且评测使用该策略选出的契约（无承诺），则存在支配策略：选平凡契约 C_triv（如 G=⊤）使测得成功率恒为 1，而真实语义成功率可为 0——**成功率指标在该博弈中不激励相容**。若执行前冻结 h(C)、成功谓词由独立求值器判定并留痕，则任何事后换契约的行为以概率 ≥ 1−ε_audit 被检出，测得成功率在已承诺契约下等于真实成功率。故：**成功率先验地要求契约外生或先冻结，否则它只是自证。** 这解释了为什么 CIG 不是可选模块，而是指标可定义性的前提。

**定理 20（安全不可谈判与拒绝可靠性）** 若 NLC 输出不能写 Σ_safe、CSA 只接受安全认证过的策略、ACR 将未认证文本降为数据，则对任意 I（含恶意注入），执行动作满足 Safe ≥ 1−ε_s；成功率优化无法用「更高成功率」换取安全放松，且不可行时的拒绝不会执行任何未认证动作。语言因此是目标接口，不是权限接口。

## 6. 本轮最大风险

**一句话**：PACT-RAS 的全部收益押在「指令→契约编译器是条款保真的」这一前提上——**若编译器悄悄丢掉一个约束、或把歧义解向更容易达成的目标，系统会为一个没人要求的任务报出漂亮的成功率；成功率优化于是不是暴露失败，而是把失败藏进契约里**——**算错了目标，成功率越高越危险。**

**次级风险与缓解**：
1. **成功率投机/目标退缩** → 契约先冻结（CIG）+ 解释/执行/判定三分离 + 定理 19 + E310；
2. **共形覆盖在分布漂移下失效** → 按条款类型/歧义层分层 + 最差层门控 + 覆盖不过即退回 R69（定义 318）；
3. **指令注入/越权目标劫持** → ACR 来源权限 + 未认证文本只作数据 + ℰ_instr 红队 + E308；
4. **不安全指令被盲从** → 安全 Σ_safe 硬约束 + 拒绝是一等输出 + 定理 20 + E309；
5. **长时程成功率逐阶段连乘过度乐观** → hazard/生存模型 + V_t^lcb + 只做边际增益最大的子契约 + E311；
6. **澄清疲劳/复述确认惹人烦** → CVE 成本项 + 预算硬约束 + 只在 SCA 时触发 + E305/E315。

## 2. 形式化定义（要点版）

**定义 310（总览与三不变式）** PACT-RAS = (NLC, SRC, SCA, CVE, CSA, CIG, RAS-WM†)；继承 R69 零学习写与交互预算；新增：契约先行并冻结、安全不可谈判、成功率只用下界。

**定义 311（指令→契约后验）** 指令 I 编译为契约 C=(P,G,K,Δ,T,⪯;γ)，条款级分解；输出后验 q(C|I,o_0) 与支撑集 supp_ε(q)，不取 argmax 单点；歧义从动作模态迁移到契约空间。

**定义 312–313（成功与两种成功率）** `S_C = ∧G ∧ ∧K ∧ (T≤0)`；`SR(π;C)=P[S_C]`；`SR_lit=SR(π;Ĉ)`，`SR_sem=Σ_C q(C)SR(π;C)`；优化 SR_sem 且约束 `SR_wc=min_C SR(π;C)≥τ_min`，避免只看字面成功率。

**定义 314（SCA）** `D_ij` 成功分歧、`X_ij` 约束冲突（含越出安全包络）、`Γ_ij` 成功率差；任一超阈即 SCA。高熵但 SCA=0 为无害歧义（不问）；低熵但 SCA=1 为致命歧义（必问）。

**定义 315（安全可容许与拒绝）** 安全包络 Σ_safe 独立于 I；可容许 ⇔ 存在安全认证且 `p_lcb≥τ_min` 的策略；不可行 ⇒ 拒绝/请求放宽/交接，禁止放松安全或改写契约。

**定义 316（CVE：成功率增益）** `ΔSR(g)=E[max_π SR | g]−max_π SR`；`g*=argmax[ΔSR−c]`；SCA=0 或无正增益则冻结执行；契约复述确认是低成本高增益的首选澄清。

**定义 317（契约鲁棒与保守契约）** `π_rob=argmax_π min_{C∈supp_ε} p_lcb(π;C)`，s.t. Safe；`K_safe=∧K_C`、`G_safe=∩G_C`；若 `p_lcb(π_rob;C_safe)<τ_min` 必须澄清/交接，不得静默选最容易的候选。

**定义 318（契约条件成功率校准 CCS）** 按条款类型与歧义层分层校准；看 ECE_C 与**最差层覆盖**；不过门 ⇒ 禁用成功率驱动决策，严格退回 R69 FLUID 内环。

**定义 319（契约承诺与反投机 CIG）** 执行前冻结 h(C) 与成功谓词哈希；修订留痕（旧/新哈希、理由、批准者）；IG/GR 超阈且 SCA=1 ⇒ 独立审计/人工确认。

**定义 320（权限与冲突 ACR）** 权限级 operator/owner/bystander/untrusted_text/unauthenticated；未认证文本只作数据；高权限只能改目标不能扩安全；同级冲突拒绝仲裁；绕过安全的元指令不可执行。

**定义 321（时序成功率）** 长时程契约分解为子契约；`V_t(C)=P(S_C|ℱ_t)` 用 hazard/生存模型估计并取下界；`V_t^lcb<τ_abort` 且不可澄清 ⇒ 交接/安全中止；按边际成功率增益排序子目标，避免逐段连乘过度乐观。

**定义 322–324（干扰集/审计/证书）** `ℰ_PACT=ℰ_FLUID×ℰ_instr×ℰ_goal`（注入、劫持、谓词投毒、歧义诱导、标签投毒、目标退缩）；VQAuditor-S 审计契约冻结、SCA、成功判定独立性与拒绝恰当性；J_PACT 并入契约哈希、H_C、p_lcb、ECE_C、最差覆盖、SCA、权限链、maximin_sr、IG。

```python
def compile_contract(I, o0, grounder, prior, k=4):

    best = None
    for g in clar_candidates(q):                      # clause/tolerance/demo/read-back/authority
        if not budget.allow(g) or not c_ras_wm.certify_info(g, o): continue
        gain = max_pi expected_sr(update(q, g), pi) - base
        best = max(best, (g, gain - cost(g)), key=lambda t: t[1])
    return best if best and best[1] > 0 else None

# IP-268/271 CSA+CRP：安全可行域内的 maximin
def admissible_robust(q, o):
    Q = support_eps(q)
    if any(not safety_certifiable(C) for C in Q): return None, "refuse_safety"
    pi = argmax_pi min_{C in Q} success_lcb(pi, C, o)
    worst = min_{C in Q} success_lcb(pi, C, o)
    if worst < TAU_MIN: return pi, "clarify_or_handover"
    return pi, "execute"

# IP-274 主闭环（R69 只作内层执行器；外层管契约）
def PACT_round(M, I, obs):
    q, h = M.nlc.compile_contract(I, obs.o0)
    if M.ccs.gate_failed(q): return M.fluid_ras_round(obs)   # 不信任成功率 -> 退回 R69
    sca = M.sca.success_critical(q, obs.env)
    g = M.cve.choose_clarification(q, I, obs) if sca else None
    if g is not None: q = M.cve.update(q, M.cve.execute(g))
    pi, mode = M.crp.admissible_robust(q, obs)
    if mode == "refuse_safety":       return M.refuse("unsafe_or_infeasible", h)
    if mode == "clarify_or_handover": return M.handover(I, q, h)
    h_exec = M.cig.commit(q)                                 # 冻结契约，防投机
    action, U = M.fluid_ras_round(obs)                       # 内层不变，不改安全包络
    M.vq_s.audit(h, h_exec, q, action, U)
    return action, M.j_pact.build(h, h_exec, q, pi, U)
```

## 4. 推导

**引理 19（熵对成功率不单调）** 存在 q：H_C 高但 SCA=0、ΔSR=0（无害歧义）；也存在 q′：H_C≈0 但 SCA=1、ΔSR≈1（致命歧义，如「停/走」）。故仅由 H_C/H_mode 触发的澄清必然同时「白问」与「漏问」；SCA 必须定义在成功/安全事件上。系：R69 的 VoI=ΔH 在契约层应改为 ΔSR。

**引理 20（成功率下界的有效性条件）** 可交换性下，分层共形/二项下界满足 `P(SR≥p_lcb)≥1−α`；指令/环境漂移时边际覆盖不等于条件覆盖，必须按条款类型与歧义层分层，并看最差层覆盖，否则总体 95% 可能掩盖某类条款 60% 的真实覆盖。

**引理 21（澄清增益上界）** `ΔSR(g) ≤ P(SCA)·max D_ij ≤ 1`；非 SCA 的澄清增益恒为 0。系：预算只投给「SCA 质量大、成本低、判别力高」的条款；SCA=1 时复述确认通常增益/成本比最高。

**定理 18（PACT 严格包含 R69）** A99–A101（编译器条款保真、成功率校准有效、权限链可信）下，PACT 的最坏契约成功率不低于 R69；安全由 Σ_safe 与拒绝语义保证，效率由澄清与 maximin 获得；q 为点质量且 SCA=0 时逐指令相同。R69 = 「单契约 / 不澄清 / 不预测成功率」边界。

**定理 19（成功率的不可投机性）** 若契约选择在被考核策略的动作空间内且评测使用其选出的契约，则存在支配策略选平凡契约 C_triv（G=⊤），使测得成功率恒为 1 而语义成功率可为 0——**成功率指标不激励相容**。若执行前冻结 h(C)、成功谓词由独立求值器判定并留痕，则事后换契约以概率 ≥1−ε_audit 被检出，测得成功率在已承诺契约下等于真实成功率。故契约必须先冻结，否则成功率只是自证。

**定理 20（安全不可谈判与拒绝可靠性）** NLC 不能写 Σ_safe、CSA 只接受认证策略、ACR 把未认证文本降为数据 ⇒ 对任意 I（含恶意注入）执行动作满足 Safe≥1−ε_s；成功率优化无法用「更高成功率」换取安全放松；不可行时的拒绝不执行任何未认证动作。语言是目标接口，不是权限接口。

## 7. 本轮最大风险

**一句话**：PACT-RAS 的全部收益押在「指令→契约编译器条款保真」这一前提上——**若编译器悄悄丢掉一个约束、或把歧义解向更容易达成的目标，系统会为一个没人要求的任务报出漂亮的成功率；成功率优化于是不是暴露失败，而是把失败藏进契约里**——**算错了目标，成功率越高越危险。**

**次级风险与缓解**：成功率投机/目标退缩（CIG 契约冻结 + 解释/执行/判定三分离 + 定理 19 + E310）；共形覆盖在漂移下失效（分层校准 + 最差层门控 + 不过门退回 R69）；指令注入/越权（ACR + 未认证文本只作数据 + ℰ_instr 红队）；不安全指令被盲从（Σ_safe 硬约束 + 拒绝一等输出 + 定理 20）；长时程连乘过度乐观（hazard/生存模型 + V_t^lcb + 边际增益排序）；澄清疲劳（CVE 成本项 + 预算 + 仅 SCA 触发）。
