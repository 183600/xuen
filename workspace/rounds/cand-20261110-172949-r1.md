# 第 46 轮（承接第 45 轮 v10；本轮灵感：柔顺控制 × 关节驱动） · Compliance-Actuation-Cert：柔顺-驱动联合证书与接触上下文驱动的力-位-能-热四元安全（四层架构 v11）

> 承接第 45 轮 v10 Energy-Context-Depth。v10 把姿态证书 P_t、能量租约 ℓ_e、上下文预测和深度门控统一起来，但仍隐含假设 H5：**关节执行器是“理想力矩源”**——力矩无限、带宽无限、无热降额、无背隙/摩擦，且指令阻抗可被精确实现。UniBot 的真实接触任务（递物、擦拭、插拔、扶人）恰恰要求柔顺控制；而柔顺控制在物理上由关节驱动兑现。一旦力矩饱和、驱动过热降额、背隙/摩擦或控制频率下降，指令刚度 K_d 会被静默截断，实际刚度 K_eff 可能远高于期望，位姿证书依然 sound，接触力却已越界。两个灵感词因此命中 H5：**柔顺控制**把安全从“别撞上”推进到“接触时注入多少力/能量”；**关节驱动**给出力的物理上限与健康状态。二者耦合出的新问题是：**当感知调度、能量租约和接触上下文共同改变控制频率与力矩需求时，如何签发一个同时覆盖位姿、接触力、关节能力与热约束的联合证书，并在执行器能力退化时 fail-closed，而不是让柔顺控制器静默退化为刚性或失稳。**

## 0. 直觉与动机

**灵感 1（柔顺控制 → 从几何安全到接触能量安全）**
直觉：刚性位置控制的安全边界是“不碰撞”；柔顺控制的安全边界是“即使接触，力和能量也有界”。导纳/阻抗控制把机器人变成一个可编程弹簧-阻尼器，低刚度通常更安全，但会牺牲任务精度与效率；更关键的是，柔顺并不自动安全——无源性能量罐耗尽、接触刚度突变、采样频率下降都可能让“柔软的控制器”在接触瞬间产生刚性冲击。因此柔顺需要一张**力证书**：在给定接触上下文下，实际接触力及其积分能量落在安全集合内。

**灵感 2（关节驱动 → 力矩是物理货币，且有热预算）**
直觉：笛卡尔空间里命令的刚度，最终要由每个关节的力矩兑现。关节能力不是常数：τ_max 随温度、转速、母线电压、电流上限和健康度变化；持续接触任务会让驱动器发热降额，背隙和摩擦会让实际位移/力偏离模型。若某个关节在接触瞬间饱和，控制器并不会“变软”，而是**悄悄变得比指令更硬或方向错误**。因此需要把关节驱动能力提升为与姿态租约、能量租约并列的**第三根信任腿**：驱动租约 ℓ_a。

**灵感 3（深度/上下文/语音/记忆 → 接触先验与刚度前置）**
直觉：不同接触对象的“安全刚度”完全不同——扶人是低刚度、大顺应；插拔是中等刚度、需要力反馈；抓取易碎物需要力上限；刚性装配反而需要较高刚度抑制颤振。v10 的深度与上下文、v23 的语音/记忆可以提供接触类型与任务意图的先验，使系统在接触发生前就选好柔顺模式并预留力矩/热预算，而不是接触后再被动限幅。

**耦合升级（v11）**：在 v10 四层架构上新增 **Compliance-Actuation Envelope（CAE）层**。IP-69 JAL 维护关节驱动租约与热/健康状态；IP-70 CAC 签发柔顺-力证书，并显式建模力矩饱和下的实际刚度退化；IP-71 CPD 用上下文/语音/记忆预测接触类型，选择柔顺模式并预留执行器能力。四层 v11：根信任层增加驱动租约 ℓ_a；L1 几何层在姿态证书外增加接触几何与力证书；L2 上下文层预测接触类型与刚度需求；L3 CAR 守卫同时检查 P_t、R_t^F、ℓ_a；L4 DCL 采集接触力、关节热与饱和事件。

## 1. 形式化定义（增量：定义 59–63）

**定义 59（关节驱动租约与能力包络）**
对关节 i，状态 x_i=(q_i, q̇_i, T_i, h_i)，其中 T_i 为驱动器温度，h_i 为健康度（背隙、摩擦、饱和历史、编码器一致性）。能力包络
A_i(q,T,h)={τ_i : |τ_i| ≤ τ_max,i(q,T,h), |τ̇_i| ≤ τ̇_max,i, T_i ≤ T_warn,i}。
热演化上界 T_i(t+Δ) ≤ T_i(t)+α_i τ_i²Δ − β_i(T_i−T_amb)Δ。驱动租约
ℓ_a=(A, τ_a, τ̇_max, T_warn, h_min)，
**可行判据**：τ_i(t+δ)∈A_i 且 T_i(t+δ)≤T_warn,i 且 h_i≥h_min 对 δ∈[0,τ_a] 成立。失效时所有依赖 ℓ_a 的力/位姿证书级联失效，控制器进入低刚度安全模式或 fail-closed。

**定义 60（无源柔顺控制与饱和感知的实际刚度）**
笛卡尔阻抗律
F_d=K_d(x_d−x)+D_d(ẋ_d−ẋ)+F_ff，
其中 K_d,D_d≻0。无源充分条件：能量罐 E_tank≥0，且 D_d ≻ (T_s/2)K_d + B̂，B̂ 为接触阻尼下界，T_s 为控制周期。关节力矩 τ=J^T F_d，若逐关节饱和 τ^sat=Sat(τ)，则实际接触力与等效刚度
F_real=J^{−T}Sat(J^T K_d Δx)，K_eff=J^{−T}S J^T K_d，
S=diag(s_i), s_i=τ_i^sat/τ_i（τ_i≠0）。因此
‖F_real−F_d‖ ≤ ‖J^{−T}(S−I)J^T K_d‖·‖Δx‖。
**关键结论**：饱和使 K_eff 不再对称且通常偏离 K_d，力证书必须显式包含饱和项，而不能只校准名义阻抗。

**定义 61（柔顺-力证书）**
接触力集合
R_t^F={F : ‖F−F_d‖≤ρ_F, F_n≤F_safe, ∫_{t}^{t+Δ}F·v dτ≤E_contact^max}。
ρ_F 由分层共形校准得到：ρ_F=Q_{1−α}({‖F_real−F_d‖}_{calib})，并按接触类型/刚度/饱和程度分层。**力 soundness**：
P(F_t∈R_t^F | c_t, K_d, ℓ_a 有效) ≥ 1−α_F。

**定义 62（柔顺-驱动联合证书）**
联合证书
J_t=(P_t, R_t^F, ℓ_p, ℓ_e, ℓ_a, m_t, K_d)。
**联合 soundness**：在 ℓ_p、ℓ_e、ℓ_a 均有效的区间内，
P(X_t∈P_t ∧ F_t∈R_t^F | ω_t,m_t,K_d,ℓ_a) ≥ 1−α，
且热/力矩/能量约束持续满足。任一租约过期 ⇒ 联合证书失效 ⇒ CAR fail-closed。
**退化传播**：若力矩饱和比例 s_min=min_i s_i，则有效力半径扩张
ρ_F^eff ≤ ρ_F + L_s(1−s_min) + L_T(T−T_warn)_+ + L_h(h_min−h)_+。

**定义 63（接触上下文驱动的柔顺调度）**
策略
π(v_t,c_t,ω_t,B_t,x_t)= (K_d,D_d,m_t)
求解
max U = E_{contact~P(·|v_t,c_t,ω_t)}[TaskGain(K_d,contact) − λ_F·Risk_F(K_d,contact) − λ_T·Heat(K_d) − λ_E·E_cost(m_t)]
s.t. τ∈A(q,T,h), E_tank≥0, E(t+Δ)≥E_min。
**风险前置**：若 P(contact∈{human,fragile}|v_t,c_t)≥τ_soft 或预测熵 H≥H_max，则强制 K_d⪯K_soft 并预留力矩裕度；若语音槽位含“轻/慢/扶/易碎”等柔顺意图，则 K_d 上限按意图收紧，且深度/力感知优先激活。

## 2. 三大新增产出与既有 IP 升级

**IP-69 JAL（Joint Actuation Lease）**
- 关节级能力包络：τ_max(q, q̇, T, 母线电压, 电流上限) 在线辨识
- 热模型与降额预测：一阶热模型 + 接触任务功率谱预测
- 健康监测：背隙/摩擦/跟随误差/饱和占空比估计
- 驱动租约签发与级联失效：ℓ_a 过期 ⇒ 力证书失效 ⇒ CAR fail-closed

**IP-70 CAC（Compliance-Actuation Certifier）**
- 无源阻抗参数校验：K_d、D_d、能量罐与采样周期联合检查
- 饱和感知实际刚度：K_eff=J^{−T}S J^T K_d，在线估计 S
- 分层共形力半径 ρ_F：按接触类型、K_d、饱和程度、温度分层校准
- 力-热-能量联合预算：接触能量积分与驱动热预算联动

**IP-71 CPD（Contact-Predictive Dispatcher）**
- 接触类型预测：刚性/软性/易碎/人/未知，输出概率与熵
- 柔顺模式选择：K_d、D_d、F_safe、力控/位控/导纳切换
- 执行器预留：提前锁定力矩裕度与热预算，避免接触瞬间饱和
- 与 MVR/VAD 联动：记忆命中复用历史柔顺参数，语音意图收紧刚度上限

**既有 IP 升级**
IP-63 ECPS：模态决策加入驱动租约约束与“接触上下文”输入，感知频率不得低于力控稳定所需下限。
IP-60 PSE：姿态证书条件化于 K_d 与 m_t；位姿与力证书共享坐标系与时间戳。
IP-61 DCL：采集任务加入接触力、关节温度、饱和事件、背隙/摩擦标签。
IP-62 CCA：新增力矩饱和注入、热降额注入、接触刚度突变、背隙/摩擦红队。
IP-51 CAR：守卫加入 F_t∈R_t^F、τ∈A、E_tank≥0；任一失败进入低刚度安全模式或停机。
IP-45 总线：新增 actuation-lease / compliance-state / force-cert / contact-context 话题。
IP-66/67/68：记忆键加入柔顺参数与接触结果；语音意图映射到刚度/力上限；SAB 绑定检查加入力证书。

## 3. 算法骨架

CAE 每控制周期：
1. 读 q, q̇, τ, T, h, B_t, ω_t, c_t, v_t
2. JAL 更新 A(q,T,h) 与外推 ℓ_a 可用区间
3. CPD 预测接触类型分布与柔顺需求，给出候选 K_d, D_d, m_t
4. CAC 检查无源条件、E_tank、力半径与饱和裕度；必要时降低 K_d
5. 若 ℓ_a 不足以支撑候选模式，则强制 K_d⪯K_safe 或 fail-closed
6. 签发 J_t=(P_t,R_t^F,ℓ_p,ℓ_e,ℓ_a,m_t,K_d)，CAR 守卫后执行
7. 接触后更新 S、ρ_F 分层校准集、热模型与记忆库；异常样本回灌 DCL

## 4. 本轮最大风险

**一句话**：柔顺证书的力半径依赖分层共形校准，而真实接触类型、负载刚度和关节饱和分布在长期任务中会漂移；若校准集覆盖不足，系统可能用一张“名义上 sound”的力证书执行实际已越界的接触，尤其在人机接触或易碎物场景造成伤害；因此必须在线监测饱和/温度/力残差，对分布漂移触发半径重校准并默认降低刚度或 fail-closed。

### IP-69 JAL

def joint_envelope(q, qd, T, h, bus_v, i_max):
    tau_nom = motor_torque_constant * i_max
    derate_T = clamp(1 - kT*max(0, T - T_warn), 0, 1)
    derate_h = clamp(h / h_nom, 0, 1)
    tau_peak = min(tau_nom*derate_T*derate_h,
                   tau_mech(q), bus_v*k_v_drop)
    return dict(tau_max=tau_peak,
                dtau_max=dtau_nom*derate_h,
                T_warn=T_warn)

def thermal_step(T, tau, dt, amb=25.0, alpha=2e-4, beta=0.02):
    return T + alpha*tau*tau*dt - beta*(T-amb)*dt

def actuation_lease(q, qd, T, h, horizon, traj):
    A = joint_envelope(q, qd, T, h, bus_v, i_max)
    T_pred = T
    for tau in traj[:horizon]:
        T_pred = thermal_step(T_pred, tau, dt)
        if abs(tau) > A['tau_max'] or T_pred > A['T_warn']:
            return None, T_pred   # 租约不可签发
    if h < h_min:
        return None, T_pred
    return dict(A=A, tau_max=A['tau_max'], T_pred=T_pred,
                expires=t+horizon*dt), T_pred
```

### IP-70 CAC
```
def passivity_ok(Kd, Dd, Ts, B_hat, E_tank):
    return (min_eig(Kd) > 0 and min_eig(Dd) > 0
            and min_eig(Dd - 0.5*Ts*Kd - B_hat) > 0
            and E_tank >= 0)

def saturation_matrix(tau_cmd, tau_sat):
    S = []
    for tc, ts in zip(tau_cmd, tau_sat):
        S.append(1.0 if abs(tc) < 1e-9 else min(1.0, abs(ts)/abs(tc)))
    return diag(S)

def force_certificate(Kd, Dd, dx, J, tau_cmd, tau_sat,
                      rho_F, F_safe, E_contact, E_max):
    S = saturation_matrix(tau_cmd, tau_sat)
    F_real = inv(J).T @ (S @ (J.T @ (Kd @ dx)))
    Keff = inv(J).T @ S @ J.T @ Kd
    delta = norm(F_real - Kd @ dx)
    ok = (delta <= rho_F and F_real[2] <= F_safe
          and E_contact <= E_max and min_eig(Keff) >= K_min)
    return ok, dict(F=F_real, Keff=Keff, delta=delta)

def cacs_certify(candidate, x, T, h, traj, calib):
    lease, T_pred = actuation_lease(x.q, x.qd, T, h, horizon, traj)
    if lease is None:
        return None, 'actuation'
    Kd, Dd = candidate.Kd, candidate.Dd
    if not passivity_ok(Kd, Dd, Ts, B_hat, E_tank):
        return None, 'passivity'
    tau_cmd = J.T @ (Kd @ dx + Dd @ dv + candidate.Fff)
    tau_sat = clip(tau_cmd, -lease.tau_max, lease.tau_max)
    rho = calib.radius(contact_type=candidate.contact,
                       Kd=Kd, sat=norm(tau_sat)/norm(tau_cmd))
    ok, cert = force_certificate(Kd, Dd, dx, J, tau_cmd, tau_sat,
                                 rho, candidate.F_safe,
                                 candidate.E_contact, E_max)
    if not ok:
        return None, 'force'
    return dict(P_t=candidate.P_t, R_tF=cert, lease_a=lease,
                Kd=Kd, Dd=Dd), 'ok'
```

### IP-71 CPD

def contact_predict(v_t, c_t, omega_t, M):
    # 语音槽位 + 上下文 + 记忆 + 深度分层
    slots = parse_voice(v_t)
    p_voice = intent_to_contact(slots)       # 轻/慢/扶/易碎/夹紧
    p_ctx = context_to_contact(c_t, omega_t) # 任务/物体/场景
    p_mem = memory_contact_prior(v_t, c_t, M)
    P = normalize(w_v*p_voice + w_c*p_ctx + w_m*p_mem + eps)
    return P, entropy(P)

def choose_compliance(P, B_t, h, v_t):
    if P['human'] + P['fragile'] >= tau_soft or entropy(P) >= H_max:
        Kd = K_soft
        reserve = 1.5 * tau_soft_margin
    elif P['rigid'] >= tau_rigid:
        Kd = K_rigid
        reserve = 1.2 * tau_rigid_margin
    else:
        Kd = K_mid
        reserve = 1.3 * tau_mid_margin
    if has_slot(v_t, ['轻', '慢', '易碎']):
        Kd = min_eig_scale(Kd, k_soft)
    return Kd, reserve
```

### 全局决策 Π_CA
```
def global_decision_ca(v_t, c_t, omega_t, B_t, x_t, M, Q_safe):
    if not empty(Q_safe):
        cmd = pop(Q_safe)
        if force_cert_still_valid(cmd): return 'execute_from_queue'
    P_contact, H = contact_predict(v_t, c_t, omega_t, M)
    Kd, reserve = choose_compliance(P_contact, B_t, x_t.h, v_t)
    if H >= H_max or reserve > actuation_reserve(x_t):
        return 'fail-closed', 'contact-uncertain'
    mem_hit, dist = memory_lookup(v_t, c_t, B_t, M)
    if mem_hit and mem_hit.outcome == 'success':
        cand = mem_hit.compliance
    else:
        cand = realtime_compliance_solve(P_contact, Kd, B_t, x_t)
    cert, status = cacs_certify(cand, x_t, T, h, traj, calib)
    if cert is None:
        # 退化：降低刚度并重试一次，否则安全队列
        cand_Kd = lower_stiffness(cand, factor=0.5)
        cert, status = cacs_certify(replace(cand, Kd=cand_Kd), ...)
        if cert is None:
            push(Q_safe, v_t); return 'queued', status
    B_prob = safety_bind(v_t, cert.P_t, cert.R_tF)
    if B_prob < theta_safe:
        push(Q_safe, v_t); return 'queued', 'bind'
    return cert, 'execute'
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| JAL 包络/热外推 | O(n_j·H) 每周期 | O(n_j) | 若 ℓ_a 有效，则 τ(t)∈A 且 T≤T_warn 对预测域成立 |
| CAC 力证书 | O(n_j³) 每次签发 | O(n_j²) | K_eff 显式含饱和矩阵 S；ρ_F 分层共形覆盖 ≥1−α_F |
| CPD 接触预测 | O(|contact|·|M|) | O(|M|) | 高熵或人/易碎先验 ⇒ 强制低刚度并预留力矩 |
| 全局决策 Π_CA | O(|M|+n_j³) | O(|Q|) | 记忆/实时/安全队列 + 三重租约 ⇒ 任一失败 fail-closed |

**正确性定理（CAC）**：设驱动租约 ℓ_a 在 [t,t+τ_a] 有效，无源条件与能量罐 E_tank≥0 成立，且分层共形半径满足覆盖 1−α_F。则 CAC 签发的联合证书 J_t=(P_t,R_t^F,ℓ_p,ℓ_e,ℓ_a,m_t,K_d) 满足：P(X_t∈P_t ∧ F_t∈R_t^F) ≥ 1−α；若力矩饱和比例 s_min<1 或温度逼近 T_warn，则 ρ_F 按定义 62 扩张，或证书拒绝签发并进入低刚度安全模式。**关键**：CAC 不允许用名义 K_d 代替 K_eff，因此不会把“饱和导致的变硬”误判为安全。

## 4. 实验设计 E115–E120

| 实验 | 指标 | 门槛 |
|---|---|---|
| E115 驱动包络与热预测 | τ_max 预测误差、温度预测误差 | τ_max 误差 ≤ 8%；温度误差 ≤ 3°C |
| E116 饱和感知力证书 | 力残差覆盖率、半径紧致度 | 覆盖率 ≥ 1−α_F（α_F=0.05）；半径不超过标称 1.5× |
| E117 柔顺稳定性 | 接触突变下超调、能量罐违例 | 超调 ≤ 10%；E_tank 违例 0 次 |
| E118 接触意图识别 | 人/易碎识别召回、刚度设置正确率 | 召回 ≥ 95%；正确率 ≥ 90% |
| E119 关节健康补偿 | 背隙/摩擦估计误差、跟随误差 | 背隙误差 ≤ 0.2°；跟随误差下降 ≥ 30% |
| E120 100h 接触-rich 闭环 | 力越界次数、热停机、任务成功率 | 力越界 0 次；热停机 0 次；成功率 ≥ 95% |

**回退策略**：E115 热预测误差 > 5°C → 缩短租约 τ_a 并提高散热裕度；E116 覆盖率 < 90% → 扩大 ρ_F 并降低 K_d 上限；E117 出现能量罐违例 → 强制增加阻尼或切位控；E118 人/易碎召回 < 90% → 默认低刚度 + 要求语音确认；E120 出现任一力越界 → 停用记忆柔顺复用，回退实时保守求解。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 力矩饱和导致 K_eff 偏离 K_d | 高 | CAC 显式计算 S 与 K_eff；饱和占空比超阈值强制降刚度 |
| 热降额使持续接触任务中途失去力矩裕度 | 高 | JAL 热外推 + 接触任务功率谱预留；超温前主动降载 |
| 力证书校准集覆盖不足 | 高 | 分层共形 + 在线残差监测 + 漂移触发重校准 |
| 语音柔顺意图误识别 | 中 | 低置信槽位进入安全队列；默认低刚度 + 二次确认 |
| 记忆复用历史柔顺参数失效 | 中 | 记忆键含 K_d/F_safe/接触 outcome；驱动租约不匹配则禁用 |
| 背隙/摩擦模型误差 | 中 | 在线辨识 + 用外感受力/位姿残差校正；保守半径 |

## 6. 本轮最大风险

**一句话**：力证书的 soundness 依赖“接触类型-刚度-饱和”分层校准与热/背隙模型，一旦真实接触分布或执行器健康发生漂移而系统未及时重校准，柔顺控制器可能在名义安全参数下产生真实越界接触力；因此必须把在线力残差、饱和占空比与温度作为证书有效性的实时守卫，任一超阈即降刚度或 fail-closed。
