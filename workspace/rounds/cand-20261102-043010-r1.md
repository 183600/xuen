# 第 1 轮（承接第 10–12 轮）· TRIAGE-SM：把「单次 VLA 执行」改成「带预算、可恢复、可审计的运行时状态机」——30% 的天花板下，赢家可能是最会失败的人

> 检索/复核日期：**2026-11-02（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新一轮灵感循环的第 1 轮，三个词是「状态机」「能耗优化」「伦理与合规」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO；它补的是这三轮共同缺的一层：**episode 级的运行时决策**。第 12 轮把「最后 3 厘米」从开环变成 5 步闭环；本轮要回答的是：**当闭环也救不回来时，机器人应该重试、让行、止损，还是转去拿步骤分？**

## 本轮的研究路径（先核实，再推进）

1. **身份**：抓官网、挑战赛页、提交仓库、HF 集合；未发现其他 UniBot 指向，按宇树展开。
2. **规则/API**：抓中英文参赛手册、提交 README；确认单模型、32 任务、10 次/任务、5 类泛化、180s、N 端口、单任务通道；确认 API 没有 depth/force/tactile/energy。
3. **榜单**：抓 leaderboard/runs/details/JSON；发现 `generated_from=gen_leaderboard.py`、逐模型 `step~success` R²>0.999999、跨模型任务相关 0.0975、成功率非 10% 整数倍 → 只当预览，不当失败分布。
4. **数据**：逐数据集读 `meta/info.json`（33,276 eps / 169.28h / 6.22–37.57s）；下载 HangCup/StackBowls/ZipUp 的部分 parquet，统计抓取事件、时长、运动学工作代理、抓取接近速度。
5. **文献**：查 Simplex/RTA、shielding、SafeVLA、Energy-Regularized IL、Energy-aware RL、Behavior Trees、Green AI、EU AI Act、NIST AI RMF；确认「运行时保证 + 能量代理 + 合规」可组合，但没人按本赛事约束组合。
6. **决策**：不推倒 CHUNK-SERVO，而是加一层 **TRIAGE-SM**：任务图 + 监控 + 预算化恢复 + 不可逆保护 + 人类让行 + 合规审计。

## 0. 先给结论：30% 不是「再准一点」的问题，是「失败之后怎么办」的问题

截至 2026-11-02，官网榜单仍是 8 个模型：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。头尾只差 9.2pp，步骤分 39.0–28.1。榜首不到 30%，说明所有模型共享同一个结构性瓶颈，而不是某个架构差一点。

但本轮先做了一个可能不太讨喜的判断：**这个共享瓶颈不只发生在「最后 3 厘米」，也发生在「失败后的 180 秒」。**

三个新核实的事实把判断推向这里：

1. **榜单是预览，不是失败分布。** `leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`；8 个模型逐模型做 `step ~ success` 回归，R² 都在 0.9999996 以上，最大残差 <0.006；32 个任务成功率的两两平均 off-diagonal 相关只有 **0.0975**；99.6% 的「模型×任务」值不是 10% 的整数倍。每任务只有 10 次 trial，真实成功率只能是 0/10、1/10、…、10/10。**所以不要把榜单的任务排名当难度表，也不要用它反推失败类型。**
2. **成功演示本身是「多段」的。** 我们对 HangCup / StackBowls / ZipUp 的部分 parquet 做了事件统计：HangCup 有 **42.0%** 的成功 episode 出现 ≥2 次「张开→闭合」抓取事件；StackBowls 全部 episode 至少 3 次；ZipUp 中位数 5 次。HangCup 里 ≥2 次抓取的 episode，时长是单次抓取的 **1.44×**，运动学工作代理是 **2.03×**。**单次开环 chunk 与数据分布本身就不匹配。**
3. **180 秒其实允许重试，但长任务不允许挥霍。** 32 任务平均时长 6.22s–37.57s；按平均时长算，HangCup 在 180s 内约有 **28.9** 次尝试预算，ZipUp 约 **12.7** 次，ToolboxStorage 只有 **4.8** 次。**重试不是免费的；它必须被预算。**

再加上两条硬约束：

- **API 没有 depth、camera_info、force/torque、tactile，也没有 battery/current/voltage。** 能耗只能做运动学/计算代理，不能声称在优化「实测焦耳」。
- **单模型规则禁止再加载第二个学习策略。** 恢复不能是一个学习出来的 residual policy；它必须是确定性控制器/状态机。

所以本轮的押注是 **TRIAGE-SM**（Task-level Runtime Integrity, Allocation, and Guarded Execution · State Machine）：

> 把 VLA 的 30 步 action chunk 当成一次「提案」，由一个确定性的运行时状态机决定：执行、修正、重试、让行、止损，还是转去拿步骤分。状态机的输入是几何/本体信号和任务图，不是第二个神经网络；它的预算单位是 **180 秒、运动学工作代理、步骤分**；它的硬约束是 **不可逆动作保护、人类让行、单模型合规**。

一句话：**把「一次预测 1 秒的动作」改成「一次提案 + 一次可审计的运行时决策」；在不新增学习模型的前提下，把 70% 的失败拆成「可恢复 / 该让行 / 该止损 / 该拿步骤分」四类。**

三个可验证创新点（不是三个宏大名目）：

1. **DEMO-GRAPH**：从 33k 成功演示的事件序列（抓取开合、EE 停顿、阶段时长）离线归纳每个任务的子目标图；用它做运行时进度监控和步骤分估计。它不输出动作，只做「现在走到哪、是否偏航」的判定。
2. **BUDGET-RECOVER + SALVAGE**：为每个失败签名（没抓到、滑移、卡住、对不准、人类编辑）准备确定性恢复原语；用 `(成功价值 + 步骤分增量) / (时间 + λ×能量代理)` 选原语；当成功概率低时切换到 SALVAGE，优先完成安全子目标、锁住步骤分，而不是冒险把已有进度归零。
3. **GUARD-ETH + ECO-CONTACT**：不可逆动作前强制 VERIFY；人类进入/移动时 YIELD；接触前限速/限 jerk；VLA 只在子目标边界或监控报警时调用，降低 GPU 计算能耗；提交包内置推理防火墙、模型哈希、隐私日志，证明「单模型 + 无在线学习 + 无原始图像留存」。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **状态机** | 任务图 → 分层 FSM：LOCALIZE / APPROACH / ALIGN / GRASP / LIFT / TRANSPORT / PLACE / RELEASE / VERIFY / RECOVER / YIELD / SALVAGE / SAFE_STOP；转移由几何/本体谓词触发 | 不做 32 个 per-task 学习策略；不把状态机做成第二个神经网络 |
| **能耗优化** | 运动学工作代理 + 计算代理 + 保持代理；接触前限速、限 jerk；VLA 事件触发；多端口 token bucket/热调度 | 不声称能读电池/电流；不为省电牺牲动态任务（传送带）的节拍 |
| **伦理与合规** | 不可逆动作 VERIFY、人类让行、隐私日志、推理防火墙、模型卡/安全案例、无跨 trial 学习 | 不做人脸识别/身份识别；不把评测图像留存；不利用评测数据在线调参 |

## 1. 本轮新核实/修正的事实（只列会改变方案的）

### 1.1 规则：单模型、32 任务、10 次/任务、5 类泛化、180 秒、N 端口（A）

官方参赛手册（中文/英文，经 `r.jina.ai` 于 2026-11-02 抓取）明确：

- 所有任务须基于**同一模型**完成，不得混合多个模型一起测试；模型类型不限（World Model、VLA 均可）。
- 32 个任务，每个任务 10 次独立运行；5 类泛化各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
- 单次真机执行上限 **180 s**；排名先看 32 任务总平均成功率，成功率相同看总平均步骤分，再相同看更早提交。
- 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态必须隔离。
- 另有**不计分的单任务测试通道**，可用于单任务成功率/步骤分验证。
- 提交方式：注册账号 → 提交模型 → 在 profile 页预约评测时段。评测时段是有限资源，不能假设无限 A/B。

**对方案的约束**：TRIAGE-SM 必须每端口独立、CPU 轻量、不抢 GPU；VLA 是唯一学习模型；状态机/监控/恢复是确定性控制器；单任务通道是唯一敢做 A/B 的地方。

### 1.2 API：四路 RGB、无深度/力/触觉、chunk 固定、EE 绝对位姿（A）

提交模板 README（2026-11-02 复核）给出：

- 观测：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB 480×640；双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str`。
- 动作：`joint` 或 `ee` 互斥；`action_chunk_size` 固定；`meta.token` 每次 `get_action` 都要带。
- `obs_delta_indices` 决定传哪些键、堆叠几帧；`image_resize` 可缩放。**没有 depth、camera_info、force/torque、tactile、battery/current。**
- README 明确：`action_chunk_size` 是每次 `get_action` 返回的 leading time-axis 长度；index 0 先执行，其余按顺序执行，直到 evaluator 再次调用 `get_action`。**chunk 内没有新的观测，也没有打断机制。**
- 评测端逐调用记录延迟、波动和动作统计规律，作为结果可信度的一部分。

**关键推论**：如果 chunk=30、控制频率 30Hz，一次 `get_action` 之后有 **1 秒开环执行**；如果 RTT=100ms，实际「看到的世界」比动作晚 100ms 以上。状态机只能在 chunk 边界决策，所以 chunk=5–8 比 30 更适合恢复；README 把 `action_chunk_size` 作为 metadata 字段、在 handshake 读取，**本报告按固定处理，不假设能在线改**。

### 1.4 榜单取证：29.7% 是「预览上限」，不是可复现 SOTA（A+B）

官网榜单（2026-11-02，经 `r.jina.ai`）：

| 排名 | 模型/用户 | 平均成功率 | 步骤分 |
|---|---|---:|---:|
| 1 | MolmoAct2 / DexHacker | **29.7%** | 39.0 |
| 2 | WALL-OSS-0.5 / Generalist Robotics | 28.5% | 38.9 |
| 3 | DreamZero / World Model Lab | 27.9% | 37.9 |
| 4 | Spirit-v1.5 / VLAGO | 25.9% | 34.4 |
| 5 | DM0 / Embodied AI Institute | 23.5% | 31.7 |
| 6 | π0.5 / RoboReasoner | 22.8% | 30.6 |
| 7 | GigaBrain-0 / xembody | 22.6% | 29.5 |
| 8 | GR00T N1.5 / Humanoid Dynamics | 20.5% | 28.1 |

取证分析（B，基于公开 JSON 的复现）：

1. `leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`。
2. 8 个模型逐模型做 `step_score ~ success_rate` 回归：**R² = 0.9999996–0.9999999，最大残差 0.0044–0.0060**；斜率 1.305–1.371。这不是实测步骤分，是脚本生成的线性缩放。
3. 8 个模型的 32 维任务成功率两两相关，**平均 off-diagonal 相关系数 0.0975**；最大 0.353，最小 -0.208。若任务难度真实，不同模型的任务级成功率应正相关。
4. 每任务只有 10 次 trial，但 256 个「模型×任务」值中有 255 个（99.6%）不是 10% 的整数倍（如 27.29%、27.85%、33.4%）。真实 10 次 trial 只能是 0/10、…、10/10。
5. 详情页 `details.html?...&task=...` 的视频仍显示「测试视频占位，后续可替换为真实视频文件」。

**结论**：把 29.7% 当赛事方给的「预览上限/难度信号」可以；把它当 SOTA、任务难度表、失败分布，都不可以。本轮不从榜单任务排名挖创新点，只从**公开规则/API/数据/官方基座**里挖。

### 1.5 本轮先导实验：成功演示本来就是多段、可重试的（B）

我们下载了三个任务的部分 parquet（不是全量）：

- HangCup：`data/chunk-000/file-001.parquet`，episodes 719–1042，324 episodes，63,999 frames。
- StackBowls：`data/chunk-000/file-002.parquet`，episodes 836–978，143 episodes，40,550 frames。
- ZipUp：`data/chunk-000/file-003.parquet`，episodes 922–1005，84 episodes，31,059 frames。

方法：30fps；夹爪读数 <2.0 记为闭合；统计「张开→闭合」事件；计算 `W = Σ(||q̇||² + 0.01||q̈||²)Δt`（归一化运动学工作代理，不是焦耳）；在抓取闭合前 5 帧估计接近速度。

| 任务 | 中位时长 | 抓取事件中位数 | ≥2 次抓取 | 180s/中位时长 | W 中位数（左/右） |
|---|---:|---:|---:|---:|---:|
| HangCup（324 eps） | 6.20 s | 1 | **42.0%** | **29.0** | 6.7 / 46.0 |
| StackBowls（143 eps） | 9.13 s | 3 | 100% | 19.7 | 35.0 / 72.4 |
| ZipUp（84 eps） | 11.53 s | 5 | 100% | 15.6 | 21.5 / 19.5 |

HangCup 内部再分：

| 子集 | n | 中位时长 | 中位 W |
|---|---:|---:|---:|
| 仅 1 次抓取 | 188 | 5.48 s | 32.7 |
| ≥2 次抓取 | 136 | **7.90 s（1.44×）** | **66.4（2.03×）** |

抓取接近速度（闭合前 5 帧，m/s）：

| 任务 | p10 | p50 | p90 |
|---|---:|---:|---:|
| HangCup（478 次事件） | 0.027 | 0.057 | 0.114 |
| StackBowls（180 次事件） | 0.042 | 0.076 | 0.128 |
| ZipUp（223 次事件） | 0.031 | 0.059 | 0.089 |

> 臂别：HangCup 统计右臂；StackBowls / ZipUp 统计左臂（该任务的主操作臂）。

**解释**：

- 成功演示不是「一次抓取就结束」。HangCup 有 42% 出现二次抓取；StackBowls/ZipUp 的多段是任务本身（三个碗、多次拉拉链）。**单次 chunk 的 VLA 在结构上无法表达「第 2 次抓取」这种事件。**
- 多段 episode 的时间是 1.44×、运动学工作是 2.03×。**重试要花时间/能量，必须预算。**
- 抓取接近速度中位数 5.7–7.6 cm/s，p90 8.9–12.8 cm/s。**若接触前限速到 5 cm/s，抓取瞬间的动能代理在中位 episode 上降 23–57%，在 p90 上降 68–85%。** 这是「能耗优化」与「接触成功」的交点，不是两个独立目标。

**边界**：这是部分文件、全部成功演示、抓取事件不等于失败/重试、W 不是焦耳。结论只用于「设计假设」，不用于宣称真机涨点。

### 1.6 头部方案的做法与瓶颈：四种路线，同一个「单次执行」

榜单名字对应公开模型家族；具体实现本轮没有逐一核实，只作背景：

| 模型家族 | 公开路线（低置信度） | 与本轮相关的瓶颈 |
|---|---|---|
| **MolmoAct2** | action reasoning + 3D 空间推理 + 双臂 | 仍是 action chunk 开环；失败后无恢复 |
| **WALL-OSS-0.5** | VLA（VLM + action expert，具体规模未在本轮核实） | progress ≠ success；最后一步失败就 0 分 |
| **DreamZero** | video-diffusion world-action model（具体规模未在本轮核实） | 推理重、chunk 长；世界模型不解决「现在偏了 2mm」 |
| **Spirit-v1.5 / DM0 / π0.5 / GigaBrain-0 / GR00T N1.5** | 通用 VLA / 世界模型生成数据 / 人形生态 | 接触精度、远程延迟、失败恢复 |

共同点不是「模型不够大」，而是：

- 都输出 action chunk，chunk 内不看新图；
- 从公开材料看不到显式的 **失败检测 → 恢复 → 预算** 层；
- 从公开材料看不到把 **步骤分** 当成运行时目标的机制；
- 从公开材料看不到把 **人类让行/不可逆保护** 做成硬约束的机制。

### 1.7 为什么现在能做：运行时保证 + 能量正则 + 合规工具已经就位

- **Runtime Assurance / Simplex**：把高性能学习控制器与可验证安全控制器配对，监控器不满足条件就切换。相关路线包括 Simplex（RTAS 2009）、Synergistic Simplex（arXiv 2605.08190）、shielding（arXiv 1708.08611）。
- **SafeVLA**（arXiv 2503.03480，NeurIPS 2025 Spotlight）：用 CMDP + safe RL 把安全约束学进 VLA。它证明「安全」是热点，但需要训练；我们的路线是**推理时运行时保证**，不改 WLA 权重，更符合单模型规则。
- **Energy-Regularized IL**（arXiv 2609.18164，ECCV 2026 Workshop）：用关节力矩×角位移定义机械功代理，微调策略降 2.1% 功、成功率 +0.7pp。它证明「能量代理可优化」，但它需要力矩/仿真；我们只有位置，所以用运动学代理。
- **Energy-aware RL**（arXiv 2602.12288）：把执行能量写进 CMDP，降 16–30% 能耗、少 16–32% 步数。它支持「能量预算」的形式化，但仍是训练一个策略；我们是运行时预算。
- **Behavior Trees**（arXiv 1709.00084）：模块化、可分析的任务切换结构；我们借它的「反应式优先级 + 形式分析」，但用确定性 FSM/STL（Signal Temporal Logic）监控，不引入 LLM。
- **Green AI**（arXiv 1907.10597）：把效率作为评价指标；对应我们的计算代理与「每成功一次的能量」报告。

**差异**：这些工作要么训练安全/能量策略，要么做通用 RTA；没有人把「单模型合规 + 远程 API + 180s + 步骤分 tie-break + 人类干扰」组合成一个**竞赛运行时状态机**。

## 2. 诊断：四个缺口，不是一个

把一次失败拆开：

```text
t0: 观测 → VLA 推理 → 返回 30 步 chunk
t0+0.1s: evaluator 开始执行 chunk
t0+0.1s … t0+1.1s: 开环执行 30 步
        ↑ 接触/滑移/人移动物体都发生在这一段
t0+1.1s: 才看到下一帧 → 已经晚了
t0+1.1s: VLA 再给一个 chunk，但它不知道刚才失败了
```

四个缺口：

1. **单次承诺（single-shot commitment）**：VLA 不检测「没抓到/滑了/卡了」，也不决定「要不要再来一次」。70% 失败里有一部分是可恢复的，但系统没有恢复入口。
2. **没有预算（no budget）**：180s 和能量代理没有被建模。短任务可以试 29 次，长任务只有 4.8 次；不分配预算的重试会把长任务直接拖到 timeout。
3. **没有护栏（no guardrail）**：人类干扰、不可逆动作（倒液、锁箱、拉拉链、插网线）没有硬约束；一次碰撞/掉落/卡死可能把整次 trial 归零，甚至造成安全风险。
4. **没有步骤分（no salvage）**：排名是「成功率 → 步骤分 → 提交时间」的字典序。当成功已经不可能时，继续冒险冲成功可能把已有步骤分清零；此时最优策略可能是 SALVAGE。

## 3. 方法：TRIAGE-SM

### 3.1 总架构

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)       │
                    │  ├─ task graph (DEMO-GRAPH)         │
                    │  ├─ progress monitor (STL/FSM)      │
                    │  ├─ recovery library + allocator    │
                    │  ├─ energy governor                 │
                    │  ├─ compliance supervisor           │
                    │  ├─ CHUNK-SERVO / plan cache        │
                    │  └─ action adapter (WLA 54D → API)  │
                    └──────────────┬──────────────────────┘
                                   │ async, batched, event-triggered
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared VLA server (GPU, one model) │
```

- **唯一学习模型**：VLA（官方 WLA 微调 action head 或直接适配）。
- **确定性控制器**：任务图、监控、恢复、能量、合规；无学习权重；不违反单模型。
- **数据资产**：33k 成功演示 → 任务图/事件统计/恢复先验；不是第二个模型，是离线索引。
- **数字孪生**：只做标定/风洞，不训练策略。

```text
   V_t = 原语节点；E_t = 观测到的转移；w_t = 该节点对应的步骤分权重（先验，待 rubric 校准）
```

```text

```

示例（ZipUp，先验）：

### 3.3 运行时监控：几何/本体信号，不引入第二个模型

| 信号 | 来源 | 用途 | 失败签名 |
|---|---|---|---|
| `grasp_closed` | 夹爪读数 | 抓取状态 | 该闭未闭 / 该开未开 |
| `r_grasp` | GEO-RESIDUAL：物体随夹爪刚性运动残差 | 是否夹住 | 没夹住 / 滑移 |
| `r_static` | GEO-RESIDUAL：物体静止假设残差 | 物体是否被移动 | 人移动物体 |
| `d_t, n_t` | 头双目/腕部几何 | 到受器距离/法向 | 对不准 / 接触过深 |
| `stall` | EE 位移 < ε 连续 K 个 chunk | 卡住 | 卡住 / 堵住 |
| `tracking_err` | 指令 EE vs 实际 EE | 碰撞/限位 | 撞到 / 被挡 |
| `edit_score` | GEO-RESIDUAL：动作解释不了的三维残差 | 人类编辑 | 人移动物体/手进入 |
| `flow_energy` | 桌面 ROI 的 Farneback 光流（确定性） | 人类/障碍物运动 | 人进入/移动 |
| `vla_uncertainty` | 同一 WLA 多采样 chunk 的方差 | 语义不确定 | 该慢/该重看 |
| `time_left` | 180s 预算 | 预算 | 该止损/该 salvage |
| `E_left` | 运动学/计算代理 | 预算 | 该降档/该 abort |
| `step_score_est` | 任务图完成节点权重 | 步骤分 | 该 salvage |

**关键**：`flow_energy` 不用人脸识别/人体检测模型；它只检测「桌面 ROI 里有无法用机器人自身运动解释的相干运动」。这既避免第二个学习模型，又避免隐私问题。

### 3.4 恢复原语与预算分配

恢复原语（全部确定性）：

| 原语 | 动作 | 前置条件 | 典型失败签名 | 风险 |
|---|---|---|---|---|
| `REOBSERVE` | 头/腕移动到标准视角，重新看 | 目标可能被挡 | 不确定/目标丢失 | 低 |
| `RETRACT(d)` | 沿接近轴后退 d | 夹爪已闭/接触中 | 卡住/过深 | 低 |
| `REALIGN` | 用相对目标重做 PBVS/IBVS | 目标可见 | 对不准 | 低 |
| `REGRASP(δ)` | 张开→偏移→闭合 | 物体可重抓 | 没夹住/滑移 | 中 |
| `RELEASE` | 张开，让物体落回 | 物体在桌面上方 | 抓错/姿态错 | 中 |
| `RETRY_SUBGOAL` | 从当前检查点重做当前节点 | 当前节点未破坏 | 任意可恢复 | 中 |
| `YIELD` | 停止/后退/等待 | 人类/障碍物 | 人类干扰 | 低 |
| `ABORT` | 安全停，保留步骤分 | 成功概率低 | 不可恢复 | 低 |

预算分配（确定性规则，不是学习策略）：

```text
对每个候选恢复原语 a：
  p = P_SUCCESS[(signature, a, phase)]      # 离线统计/单任务通道的先验，不线上更新
  gain = p * (SUCCESS_VALUE + STEP_GAIN[a]) + (1-p) * STEP_KEEP[a]
  cost = TIME[a] + LAMBDA_E * ENERGY_PROXY[a]
  utility = gain / cost
选择 utility 最高且满足：
  time_left  > TIME[a] + MIN_MARGIN
  E_left     > ENERGY_PROXY[a] + MIN_MARGIN
  precond(a) = True
  risk(a) <= risk_budget(phase)
若最高 utility < THRESHOLD：进入 SALVAGE 或 ABORT。
```

- `SUCCESS_VALUE` 远大（字典序优先成功），`STEP_GAIN/STEP_KEEP` 处理步骤分。
- `P_SUCCESS` 是离线表/单任务通道的先验，**不在评测中更新**；这避免「在线学习」和跨 trial 适应。
- `risk_budget` 在不可逆阶段收紧；接触段只允许低风险原语。

### 3.5 SALVAGE：成功无望时，别把步骤分也弄丢

排名是字典序：成功率 → 步骤分 → 提交时间。设当前估计成功概率 `p_s`，剩余时间 `T`，当前步骤分 `S_now`，可安全完成的剩余节点权重 `S_safe`：

```text
if p_s < TAU_SALVAGE or T < T_MIN:
    mode = SALVAGE
    # 只做低风险、可完成、正步骤分的节点
    # 禁止新的不可逆动作（除非已经 commit）
    # 不再为了成功做高风险插入/倾倒/拉拉链
    maximize S_now + S_safe
else:
    mode = SUCCESS
```

这不是「钻规则空子」；这是按官方 rubric 的字典序做决策。它还有一个伦理好处：成功无望时不再做高风险动作，减少损坏/伤人概率。

### 3.6 能量治理：能测的不是焦耳，是代理

API 没有电流/电压/扭矩，所以定义三个代理（归一化单位）：

```text
E_motion = Σ (α||q̇||² + β||q̈||²) Δt          # 运动学工作代理
E_compute = Σ (γ0 + γ1·H·W) · n_vla           # VLA 调用/图像分辨率代理
E_hold = δ · gripper_force_proxy · t_hold     # 夹持保持代理
E_total = E_motion + E_compute + E_hold
```

- **接触前限速**：`|v_n| <= v_safe(task, phase)`；`|jerk| <= j_max`。抓取接近速度中位 5.7–7.6 cm/s，p90 8.9–12.8 cm/s；5 cm/s 限速能把抓取瞬间动能代理降 23–57%（中位）/68–85%（p90）。
- **事件触发 VLA**：只在子目标边界或监控报警时调用 VLA；其余用 CHUNK-SERVO/缓存 plan。HangCup 6.2s 若每 30 步调用一次约 6 次；若每 5 步一次约 37 次；子目标触发可降到 1–2 次（具体以 G4 为准）。
- **多端口热调度**：共享 GPU 上做 token bucket，接触阶段优先，approach 阶段可批处理/降分辨率；监控 GPU 温度/功耗/p99，热降档时增大 chunk 或降分辨率。
- **不要**：为省电牺牲传送带等动态任务的节拍；不要在接触段用高增益追速度。

### 3.7 伦理与合规：把「安全」做成可审计的运行时层

| 约束 | 设计 | 证据/审计 |
|---|---|---|
| 单模型 | 只有 WLA 是学习模型；状态机/监控/恢复/能量全是确定性代码；不加载第二个学习策略 | `model_graph.json`：checkpoint hash + code hash + 无外部模型调用 |
| 无在线学习 | 不更新权重、不在线调阈值、不跨 trial 缓存；`reset()` 清空 episode 状态 | `reset()` 单元测试；审计日志 |
| 人类让行 | `flow_energy`/`edit_score` 触发 YIELD：停、后退、等待稳定；人类附近限速；不朝人移动 | 人类干扰脚本测试；碰撞率 0 |
| 不可逆保护 | 倒液/锁箱/拉拉链/插网线前强制 VERIFY；验证失败 → REOBSERVE/ABORT，不 commit | 不可逆任务审计；虚假 abort 率 |
| 隐私 | 不存原始图像/人脸/身份；只存状态转移、低维特征、动作哈希 | 日志 schema；保留期；访问控制 |
| 透明 | 模型卡、安全案例、失败分类、局限；提交材料写清楚 | 提交包附录 |
| 公平 | 不用隐藏状态、不利用 evaluator、不在评测中人工干预；任务图来自公开任务描述/数据 | 合规声明 |

**注意**：赛事规则没有单列「伦理评分」；伦理与合规在这里是**风险约束/差异化**，不是直接加分项。唯一直接相关的评分通道是**人为干扰泛化**（占 20% trials），YIELD 可能在这里涨点。

### 3.8 接口集成：chunk=5/8，状态机在 chunk 边界决策

- README 把 `metadata.action_chunk_size` 作为 metadata 字段、在 handshake 读取；本报告按固定处理。TRIAGE-SM 推荐 **5 或 8**：5 步 @30Hz = 167ms 决策周期；8 步 = 267ms。30 步只适合「安全基线」。
- 每个 `get_action`：
  1. 更新监控；
  2. 若人类/编辑 → YIELD；
  3. 若安全违反 → SAFE_STOP；
  4. 若不可逆且未 VERIFY → VERIFY/REOBSERVE；
  5. 若失败签名 → RECOVER/SALVAGE；
  6. 否则 VLA plan + CHUNK-SERVO；
  7. 扣预算，返回合法 chunk。
- `reset()` 清空：状态、任务图进度、plan cache、goal cache、预算、人类标志；**不**清空离线任务图/离线先验表。
- 每端口独立实例；共享 VLA server 只读权重；禁止全局可变状态。

### 3.9 形式化保证：把关键不变量写进模型检查

抽象成布尔 FSM（连续谓词用保守阈值二值化）：

```text
AG (commit -> verified)
AG (human_near -> state ∈ {YIELD, RETREAT, SAFE_STOP})
AG (irreversible_done -> !retry_irreversible)
AG (timeout -> state = SAFE_STOP)
AG (reset -> state = IDLE ∧ budget = fresh ∧ cache = empty)
AG (state = SAFE_STOP -> cmd_speed = 0)
```

用 NuSMV/Storm 在抽象模型上检查；连续阈值用区间抽象/保守上界。通过标准：所有性质无违例；反例必须能映射回真实状态，否则加不变式。这是「状态机」从流程图变成**可审计运行时保证**的关键。

## 4. 竞赛策略：320 trials 是投资组合，不是 32 个独立任务

### 4.1 算术

- 总分 `S = (1/32) Σ_t p_t`。
- 320 trials 下，`p≈0.25` 的单次标准误约 `sqrt(0.25×0.75/320)=2.42pp`；配对设计会低一些，但**不要声称 +1–2pp 是结论**。
- 人为干扰轴 = 2/10 = **20%**；`ΔS_human = 0.2 Δp_h`。human 轴 +10pp → 全局 +2pp。
- 恢复的粗算：`Δp ≈ (1-p) q r s`，`q` 是可恢复失败比例，`r` 是恢复成功率，`s` 是预算饱和因子（0.7–1.0）。

| q | r | s | Δp（p=0.25） |
|---|---:|---:|---:|
| 0.3 | 0.2 | 0.8 | +3.6pp |
| 0.3 | 0.3 | 0.8 | +5.4pp |
| 0.5 | 0.3 | 0.8 | +9.0pp |
| 0.5 | 0.5 | 0.8 | +15.0pp |
| 0.5 | 0.5 | 1.0 | +18.8pp |

**目标区间 +4–8pp；+15pp 是乐观上界，必须由 G4 证明。** 步骤分 salvage 另算：若失败 trial 平均多拿 5–10 分，`(1-p)×5~10` → 平均 +3.75–7.5 分，主要用于 tie-break。

### 4.2 任务分档：先做「短、可恢复、风险可控」的任务

用 `priority_t = q_t × r_t × B_t / cost_t`，其中 `B_t = 180 / avg_duration_t`（按平均时长估算的尝试预算上限）。

- **A 档（先做恢复）**：HangCup（B≈28.9）、StackBowls（17.9）、OrganizeBookshelf（17.5）、DisconnectEthernet（17.1）、FruitSorting（16.9）、FruitCollection（16.6）、PlacePhotoFrame（16.1）、ConveyorSorting（14.8）、ColorArrangement（13.2）、PaperCupStacking（13.0）、ZipUp（12.7）、Unlock（12.5）、PlugInEthernet（11.0）。
- **B 档（先做护栏/预检）**：ToolboxStorage（B≈4.8）、StorePaddle（5.3）、SpellRobot（5.8）、PackPhone（6.2）、FoldTowel（7.0）、StoreEarphones（7.5）、OrganizeStationery（7.5）、OrganizeTools（7.2）、PackBag（11.9）、OrganizePencilCase（8.8）、SyringeWaterTransfer（11.8）、PourOutMedicine（8.2）。这些任务预算少，重试代价高；优先 **VERIFY + 一次成功**，而不是多次重试。
- **C 档（salvage/观察）**：单任务通道里 `p_t` 接近 0 且失败在早期感知/抓取的任务；不投恢复工程，保留 VLA 基线。

这张表是**先验**，不是结论。单任务通道测完后，用 `q_t`（失败中可恢复比例）、`r_t`（恢复成功）、`B_t` 重排；每测 3–5 个任务更新一次。

### 4.3 单任务通道协议

1. 选 6 个代表任务：HangCup（短、多抓取）、PlugInEthernet（插入）、ZipUp（长程、拉链）、StackBowls（双臂堆叠）、FoldTowel（变形，负对照）、ToolboxStorage（长程、锁箱）。
2. 每个任务 10 次 A/B：baseline（WLA + CHUNK-SERVO）vs TRIAGE-SM；尽量同初始条件配对。
3. 记录：成功、步骤分、耗时、重试次数、恢复原语、能量代理、p99、碰撞/abort。
4. 通过：至少 3/6 任务 +10pp；FoldTowel 不回归 >5pp；零碰撞；timeout 不升。
5. 再扫 `chunk ∈ {5,8}`、`v_safe ∈ {0.05,0.08,0.12}`、`TAU_SALVAGE`。
6. 最后才跑 32×10 正式评测。

### 4.4 提交节奏

- **W0**：官方 WLA + API adapter + chunk 30 安全基线；单任务通道确认 token/`pivot`/`reset`。
- **W1**：DEMO-GRAPH + 监控；单任务 baseline；失败分类。
- **W2**：恢复库 + 预算；仿真/回放。
- **W3**：能量治理 + 合规；人类干扰/不可逆审计。

# 第 1 轮产物 · TRIAGE-SM 技术报告

> 检索/复核日期：**2026-11-02（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是新一轮灵感循环第 1 轮「TRIAGE-SM」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是把它们接到 **episode 级运行时决策**。

## 0. 结论与边界

### 0.1 一句话结论

榜首不到 30%，且榜单是脚本生成的预览；真正的共享瓶颈不只是「最后 3 厘米」，还有「失败之后的 180 秒」。本报告把 VLA 的 action chunk 当成一次提案，用一个**确定性运行时状态机**（任务图 + 进度监控 + 预算化恢复 + 不可逆保护 + 人类让行 + 合规审计）决定执行、修正、重试、让行、止损或 salvage；它不新增学习模型，因此符合单模型规则；它把 70% 的失败拆成可恢复/该让行/该止损/该拿步骤分四类，目标是把单次成功率变成可恢复、可审计的多尝试成功率。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、排行榜 JSON 直接核实 | 规则、API、33,276 eps、榜单 29.7%、`generated_from`、腕部内参 |
| B | 我们在公开数据/网页上做的分析，可复现 | 榜单 `step~success` 回归、跨模型任务相关、HangCup/StackBowls/ZipUp 事件统计 |
| C | 设计假设，需 G0–G9 验证 | 恢复 +4–8pp、5 cm/s 限速涨点、YIELD 恢复 ≥50% |

### 0.3 本轮不做什么

- 不从零训 VLA/World Model；官方 WLA 已开源 6B 基座。
- 不做第二个学习恢复策略/残差网络；恢复是确定性原语。
- 不做在线自适应/跨 trial 学习；`reset()` 清空，避免合规与数据泄漏风险。
- 不做 30Hz 广域网伺服；README 把 `action_chunk_size` 作为 metadata 字段、在 handshake 读取，本报告按固定处理，推荐 5/8。
- 不做 6D 物体位姿网络、力/触觉闭环；API 没有。
- 不声称能读电池/电流/电压；能耗只做代理。
- 不把榜单任务排名当难度表；榜单是预览。
- 不做 32 个 per-task 状态机；用一个任务条件化状态机。

### 0.4 创新点清单（持续迭代）

> 优先级：P0 本轮主推 / P1 次推 / P2 观察。每个点按「动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险」写。本轮新增 I1–I6；下轮按 G0–G9 的失败门修剪，不推倒重来。

#### I1 · DEMO-GRAPH（P0）
- **动机**：42% 的 HangCup 成功演示有 ≥2 次抓取；StackBowls/ZipUp 是多段任务。单次 chunk 无法表达「第 2 次抓取」。

- **技术可行性**：高。事件分段用夹爪开合/EE 速度/时长；任务图是 JSON；监控是阈值/几何；CPU <2ms。
- **所需资源**：33k 演示的 `meta/info.json` + parquet；公开任务描述；CPU；单任务通道。
- **落地步骤**：W1 做 32 任务图 → 离线边界 F1 ≥0.75 → 单任务通道验证进度监控 → 再接恢复。
- **风险**：任务图过拟合/事件定义不唯一；用多任务 schema + 人工抽检 + 消融。

#### I2 · BUDGET-RECOVER（P0）
- **动机**：180s 允许短任务 29 次、长任务 4.8 次尝试；重试有 1.44× 时间/2.03× 工作成本。没有预算的重试会把长任务拖到 timeout。
- **与现有方案差异**：现有学习恢复策略；本方案用确定性原语 + 离线 `P_SUCCESS` 表 + `(成功价值+步骤分)/成本` 分配，不新增学习模型。
- **技术可行性**：高。原语是几何/夹爪/固定轨迹；预算用时间/代理能量；每端口 CPU。
- **所需资源**：单任务通道 6 任务×10 A/B；离线失败日志；CPU。
- **落地步骤**：W2 恢复库 → 仿真/回放 → 单任务 A/B → 阈值扫描。
- **风险**：恢复造成损坏/误报；不可逆保护、限速、最大重试、风险预算。

#### I3 · SALVAGE（P0）
- **动机**：排名是「成功率 → 步骤分 → 提交时间」字典序；成功无望时继续冒险可能把已有步骤分清零。
- **与现有方案差异**：现有 VLA 只最大化成功；SALVAGE 显式优化步骤分，且只做低风险节点，成功无望时反而更安全。
- **技术可行性**：高。需要任务图权重；若 rubric 未公开，用等权/单任务通道校准。
- **所需资源**：官方 rubric/步骤分日志；单任务通道；CPU。
- **落地步骤**：W2 加 SALVAGE 模式 → 离线回放 → 单任务 A/B 测步骤分。
- **风险**：被误解为「钻规则空子」；在模型卡/合规说明中写清楚：按官方字典序优化，且成功无望时降低风险。

#### I4 · GUARD-ETH（P1）
- **动机**：人为干扰占 20% trials；不可逆动作（倒液/锁/拉链/插）一次失败可能归零；单模型规则禁止第二个学习模型。
- **与现有方案差异**：SafeVLA 用 CMDP 训练安全策略；GUARD-ETH 是推理时确定性护栏（YIELD/VERIFY/防火墙/隐私日志），不改 WLA 权重。
- **技术可行性**：高。光流/帧差 + edit_score + 本体信号；无学习模型；CPU <5ms。
- **所需资源**：脚本人类干扰；不可逆任务审计；合规文档；CPU。
- **落地步骤**：W3 人类让行 → 不可逆 VERIFY → 推理防火墙/模型卡 → G5/G6/G8。
- **风险**：光流漏检/误报；用多信号迟滞 + 保守 YIELD + 不声称 100%。

#### I5 · ECO-CONTACT（P1）
- **动机**：抓取接近速度中位 5.7–7.6 cm/s、p90 8.9–12.8 cm/s；5 cm/s 限速可降抓取瞬间动能代理 23–57%（中位）/68–85%（p90）。

- **所需资源**：MuJoCo/台架校准；单任务通道；CPU。
- **落地步骤**：W3 限速/滤波 → 仿真扫 0.05/0.08/0.12；W4 单任务 A/B → 只对静态接触任务启用。

#### I6 · COMPUTE-GATE（P2）

```python
# 30 fps; gripper < 2.0 => closed
closed = (g < 2.0).astype(int)
events = np.diff(closed)
close_events = int((events == 1).sum())
open_events  = int((events == -1).sum())
# kinematic work proxy (normalized, not joules)
vj = np.linalg.norm(np.diff(q, axis=0), axis=1) * 30

# grasp approach speed: mean EE speed in 5 frames before close
```

## 2. 问题形式化

### 2.1 字典序目标

总分与排名：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

排名是字典序：

```math
\text{maximize } \big(S,\ \bar{Step}\big)
\quad\text{s.t.}\quad
\text{safety invariants}.
```

因此运行时目标不是单一 `success`，而是：

```math
U = \mathbf{1}[\text{success}]\cdot M + \text{step\_score}
```

其中 `M` 远大于 step score，体现字典序；但在成功概率低时，`U` 退化为 step score，触发 SALVAGE。

### 2.2 预算化半马尔可夫决策过程

把 episode 建模为预算化 semi-MDP：

```math
\mathcal{M} = (\mathcal{S}, \mathcal{A}, P, R, C, T)
```

- 状态 `s = (φ, c, v, h, b_t, b_e, g)`：
  - `φ`：任务图节点/阶段；
  - `c`：接触/夹持标志；
  - `v`：目标可见/可辨识；
  - `h`：人类/障碍物标志；
  - `b_t`：剩余时间（180s）；
  - `b_e`：剩余能量代理；
  - `g`：步骤分进度。
- 动作 `a ∈ A_VLA ∪ A_servo ∪ A_recover ∪ {YIELD, ABORT, SALVAGE}`。
- 硬约束：安全不变量 `I(s,a)=True`；软约束：`E[E_total] ≤ E_max`。
- 策略：确定性规则（状态机），不是学习策略；离线表 `P_SUCCESS` 不线上更新。

### 2.3 重试价值

对失败签名 `σ`、阶段 `φ`、候选恢复原语 `a`：

```math
p = P_{\text{success}}(\sigma,a,\phi)
```

```math
\text{gain} = p\,(V_{\text{success}} + \Delta S_a) + (1-p)\,S_{\text{keep}}(a)
```

```math
\text{cost} = T_a + \lambda_E E_a
```

```math
a^* = \arg\max_a \frac{\text{gain}}{\text{cost}}
```

约束：

```math
b_t > T_a + T_{\min},\quad b_e > E_a + E_{\min},\quad
\text{precond}(a,s),\quad \text{risk}(a) \le \rho(\phi).
```

若 `gain/cost < τ`，进入 SALVAGE/ABORT。

### 2.4 能量代理

API 没有电流/电压/扭矩，定义归一化代理：

```math
E_{\text{motion}} = \sum_k \left(\alpha\|\dot q_k\|^2 + \beta\|\ddot q_k\|^2\right)\Delta t
```

```math
E_{\text{compute}} = \sum_k \left(\gamma_0 + \gamma_1 H_k W_k\right) n_{\text{vla},k}
```

```math
E_{\text{hold}} = \delta \cdot f_{\text{grip}} \cdot t_{\text{hold}}
```

```math
E_{\text{total}} = E_{\text{motion}} + E_{\text{compute}} + E_{\text{hold}}
```

- 若团队有 G1 台架/功率计：拟合 `α,β,γ,δ`，目标 `R² ≥ 0.8`。
- 若没有：只做相对排序，报告「归一化单位」，不报焦耳。
- `f_grip` 不可测，用夹爪指令/开合速度代理；不要声称是力。

### 2.5 安全不变量

抽象状态上的硬约束：

```text
I1: commit -> verified
I2: human_near -> state ∈ {YIELD, RETREAT, SAFE_STOP}
I3: irreversible_done -> !retry_irreversible
I4: timeout -> SAFE_STOP
I5: reset -> IDLE ∧ budget=fresh ∧ cache=empty
I6: SAFE_STOP -> cmd_speed = 0
```

连续层用保守阈值/区间抽象；形式检查见 §4。

### 2.6 SALVAGE 阈值

```math
p_s = f(\phi, \text{progress}, b_t, \text{failure history})
```

```math
\text{mode} =
\begin{cases}
\text{SALVAGE}, & p_s < \tau_s \ \text{or}\ b_t < T_{\min}\\
\text{SUCCESS}, & \text{otherwise}
\end{cases}
```

`p_s` 是确定性启发式（阶段/进度/剩余时间/失败次数），不是学习模型。SALVAGE 只做低风险、正步骤分节点；禁止新的不可逆动作。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)       │
                    │  ├─ task graph (DEMO-GRAPH)         │
                    │  ├─ progress monitor (STL/FSM)      │
                    │  ├─ recovery library + allocator    │
                    │  ├─ energy governor                 │
                    │  ├─ compliance supervisor           │
                    │  ├─ CHUNK-SERVO / plan cache        │
                    │  └─ action adapter (WLA 54D → API)  │
                    └──────────────┬──────────────────────┘
                                   │ async, batched, event-triggered
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared VLA server (GPU, one model) │
                    │  UnifoLM-WLA-1.0 / VLA-0            │
                    └─────────────────────────────────────┘
```

- 每个端口一个 `PolicyService` 实例，独立 `reset()`、独立任务图进度、独立预算。
- 状态机/监控/恢复是 CPU 线程，不阻塞 websocket；VLA 请求异步、可批处理。
- 共享 VLA server 用 session ID 区分端口；模型权重只有一份，不违反单模型。
- 离线任务图/先验表只读、可共享；禁止全局可变状态。

| `LIFT` | 夹住 | 抬升、物体跟随检查 | 物体跟随 | RELEASE / REGRASP |
| `TRANSPORT` | 抬升 | VLA/伺服搬运 | 到达目标区 | RETRACT / RECOVER |
| `PLACE/HANG` | 目标区 | 对齐、插入/挂/叠 | 接触稳定 | REALIGN / RETRACT |
| `RELEASE` | 放好 | 张开、稳定检查 | 物体稳定 | REOBSERVE / ABORT |
| `VERIFY` | 释放 | 多视角验证成功/步骤分 | 成功/失败 | SALVAGE / DONE |
| `RECOVER` | 失败签名 | 选原语、扣预算 | 原语完成/失败 | SALVAGE / ABORT |
| `YIELD` | 人类/障碍物 | 停、后退、等待 | 人类离开且稳定 | 恢复/ABORT |
| `SALVAGE` | 成功概率低 | 安全完成剩余节点 | 无安全节点/超时 | DONE/ABORT |
| `SAFE_STOP` | 安全违反/超时 | 停止、保持 | reset | — |
| `DONE` | 成功/失败 | 清理 | reset | — |

| 信号 | 来源 | 计算 | 阈值/用途 |
|---|---|---|---|
| `grasp_closed` | 夹爪读数 | `g < g_close` | 抓取状态 |
| `r_grasp` | GEO-RESIDUAL | 物体随夹爪刚性运动残差 | 没夹住/滑移 |

| `tracking_err` | 指令 EE vs 实际 EE | `‖p_cmd - p_state‖` | 碰撞/限位 |
| `edit_score` | GEO-RESIDUAL | 动作解释不了的三维残差 | 人类编辑 |

**人类检测**：`flow_energy` 不使用人脸/人体检测模型；只在桌面 ROI 检测「无法用机器人自身运动解释的相干运动」。配合 `edit_score` 和本体信号做迟滞（连续 2 chunk 触发，稳定 5 chunk 解除）。光流在 160×120 灰度 ROI 上做，目标 <5ms/调用；没有 OpenCV 时用 numpy 帧差/块匹配兜底；状态机/恢复决策目标 <2ms；VLA 异步，不阻塞 websocket。

### 3.5 恢复原语

| 原语 | 动作 | 前置条件 | 典型签名 | 风险 | 成本 |
|---|---|---|---|---|---|
| `REOBSERVE` | 头/腕到标准视角 | 目标可能被挡 | 不确定/丢失 | 低 | 0.5–1.5s |
| `RETRACT(d)` | 沿接近轴后退 | 夹爪闭/接触 | 卡住/过深 | 低 | 0.3–1.0s |
| `REALIGN` | PBVS/IBVS 重对齐 | 目标可见 | 对不准 | 低 | 0.3–1.0s |
| `REGRASP(δ)` | 张开→偏移→闭合 | 物体可重抓 | 没夹住/滑移 | 中 | 0.8–2.0s |
| `RELEASE` | 张开让物体落回 | 桌面上方 | 抓错/姿态错 | 中 | 0.2–0.5s |
| `RETRY_SUBGOAL` | 从当前检查点重做 | 节点未破坏 | 任意可恢复 | 中 | 1–5s |
| `YIELD` | 停/后退/等待 | 人类/障碍 | 人类干扰 | 低 | 0.5–3s |
| `ABORT` | 安全停、保留步骤分 | 成功概率低 | 不可恢复 | 低 | 0.1s |

原语实现全部确定性：几何伺服、夹爪开合、固定轨迹、光流/残差阈值；无学习权重。

### 3.6 预算分配伪代码

```python
def choose_recovery(sig, s, table):
    best = None
    for a in PRIMITIVES[sig]:
        if not precond(a, s):
            continue
        if s.time_left < TIME[a] + T_MIN:
            continue
        if s.energy_left < ENERGY[a] + E_MIN:
            continue
        if risk(a) > risk_budget(s.phase):
            continue
        p = table.success(sig, a, s.phase)      # offline prior, no online update
        gain = p * (SUCCESS_VALUE + STEP_GAIN[a]) + (1 - p) * STEP_KEEP[a]
        cost = TIME[a] + LAMBDA_E * ENERGY[a]
        u = gain / cost
        if best is None or u > best.u:
            best = Candidate(a, u, p, cost)
    if best is None or best.u < TAU_RECOVER:
        return None
    return best.a
```

规则：

- `SUCCESS_VALUE` 远大于 step score，体现字典序。
- `table.success` 来自离线演示/单任务通道；**评测中不更新**。
- `risk_budget` 在 R2 阶段收紧；R2 阶段只允许低风险原语。
- 任何异常 → 返回 `None`，由上层进入 SALVAGE/ABORT；绝不返回 NaN/错误形状。

### 3.7 能量治理伪代码

```python
def energy_update(obs, action, mode):
    q  = obs["observation.state.left_arm"] + obs["observation.state.right_arm"]
    qd = finite_diff(q, dt)
    qdd= finite_diff(qd, dt)
    E_motion  = (ALPHA * norm2(qd) + BETA * norm2(qdd)) * dt
    E_compute = (GAMMA0 + GAMMA1 * H * W) * n_vla
    E_hold    = DELTA * grip_proxy * dt_hold
    E = E_motion + E_compute + E_hold
    if E_left < E_MIN:
        mode = "ECO"          # cached plan, lower resolution, slower
    if task_dynamic:          # conveyor etc.
        mode = "TURBO"        # don't slow the beat
    return E, mode

def contact_guard(v_n, phase):
    v_safe = V_SAFE[phase]    # e.g. 0.05 m/s for fragile/liquid
    if abs(v_n) > v_safe:
        return scale_toward(v_n, v_safe)
    return v_n
```

- 接触限速：`v_safe` 按任务/阶段；液体/易碎 0.05 m/s，刚性 0.08–0.12 m/s；动态任务例外。
- jerk 限幅：二阶滤波/五次多项式，避免冲击。
- VLA 事件触发：只在子目标边界或监控报警时调用；其余用缓存 plan + CHUNK-SERVO。
- 多端口 token bucket：接触阶段优先；approach 可批处理；GPU 温度/p99 超阈值时降分辨率/增大 chunk。

```python
def pre_execute(action, s):
```

### 3.9 `get_action` / `reset` 伪代码

```python
class TriagePolicy:
    def get_action(self, obs):
        self._tick(obs)                      # budget, monitor, task graph
        s = self.state

        if self.human_or_edit(s):
            return self._yield(obs)
        if self.safety_violation(s):
            return self._safe_stop(obs)
        if self.need_verify(s):
            return self._verify(obs)
        if self.failure_signature(s):
            a = choose_recovery(s.signature, s, self.table)
            if a is not None:
                return self._recover(a, obs)
            return self._salvage_or_abort(obs)

        if self.success_prob(s) < TAU_SALVAGE or s.time_left < T_MIN:
            return self._salvage(obs)

        self._maybe_request_plan(obs)        # async, event-triggered
        a_ff = self.plan[self.plan_idx:self.plan_idx + self.H]
        a_cmd = self.servo.compose(a_ff, obs, self.goal)
        self._spend_budget(a_cmd)
        return self.adapter.to_api(a_cmd, obs, self.token)

    def reset(self):
        self.state = IDLE
        self.task_graph.reset()
        self.plan = None
        self.plan_idx = 0
        self.goal = None
        self.time_left = 180.0
        self.energy_left = E_MAX
        self.human = False
        self.irreversible_done = False
        # do NOT clear offline task graph / prior tables
```

规则：

- VLA 永不阻塞 `get_action`（除冷启动）；plan 过期就用旧 plan + 伺服。
- 每个 chunk 只做一次状态机决策；决策失败返回安全 hold。
- 任何异常 → 返回上一组合法 chunk 或 SAFE_HOLD；绝不返回 NaN/错误形状。
- `reset()` 必须清空所有 episode 状态；离线表只读。

### 4.1 抽象 FSM

把连续谓词抽象成布尔：

- `verified`：不可逆动作前的多视角/几何检查通过；
- `human_near`：光流/edit_score/本体信号触发；
- `irreversible_done`：已 commit；
- `timeout`：`b_t ≤ 0`；
- `reset`：episode 重置；

### 4.2 时序性质

```text
P1  AG (commit -> verified)
P2  AG (human_near -> state ∈ {YIELD, RETREAT, SAFE_STOP})
P3  AG (irreversible_done -> !retry_irreversible)
P4  AG (timeout -> state = SAFE_STOP)
P5  AG (reset -> state = IDLE ∧ budget = fresh ∧ cache = empty)
P6  AG (state = SAFE_STOP -> cmd_speed = 0)
P7  AG (state = SALVAGE -> !new_irreversible)
```

### 5.3 结论

1. **单次执行与数据分布不匹配**：HangCup 42% 成功 episode 有 ≥2 次抓取；StackBowls/ZipUp 的多段是任务本身。状态机必须显式建模「第 2 次抓取/多次拉链」。
2. **重试有成本**：多段 HangCup 的时间 1.44×、运动学工作 2.03×；长任务 B 只有 4.8，不能无限重试。
3. **接触限速有数据支撑**：抓取接近速度中位 5.7–7.6 cm/s、p90 8.9–12.8 cm/s；5 cm/s 限速能显著降动能代理，但时间成本需真机验证。
4. **能耗优化不是独立目标**：它和接触成功、重试预算绑在一起；状态机是它们的共同调度器。

### 6.6 消融

1. 恢复 on/off。
2. SALVAGE on/off。
3. 接触限速 0.05/0.08/0.12/off。
4. 事件触发 VLA vs 每 chunk 调用。
5. 人类让行 on/off。
6. 不可逆 VERIFY on/off。
7. `P_SUCCESS` 先验 vs 均匀先验。
8. chunk 5 vs 8。

### 6.7 统计

- 320 trials 下 `p≈0.25` 的 SE≈2.42pp；10 次/任务的标准误约 13.7pp（单任务），所以单任务只看方向，不能看显著性。
- 配对 A/B 用 bootstrap 95% CI；报告每任务差值和 pooled 差值。
- 不把 +1–2pp 当结论；目标 +4–8pp 需要 ≥3 个任务同向。

### 7.2 分档策略

用 `priority_t = q_t × r_t × B_t / cost_t`：

- **A 档（先做恢复）**：HangCup、StackBowls、OrganizeBookshelf、DisconnectEthernet、FruitSorting、FruitCollection、PlacePhotoFrame、ConveyorSorting、ColorArrangement、PaperCupStacking、ZipUp、Unlock、PlugInEthernet。
- **B 档（先做护栏/预检）**：ToolboxStorage、StorePaddle、SpellRobot、PackPhone、FoldTowel、StoreEarphones、OrganizeStationery、OrganizeTools、PackBag、OrganizePencilCase、SyringeWaterTransfer、PourOutMedicine。
- **C 档（salvage/观察）**：单任务通道里 `p_t` 接近 0 且失败在早期感知/抓取的任务；不投恢复工程，保留 VLA 基线。

**长任务原则**：B 只有 4.8–7.5，重试 1–2 次就可能 timeout；优先 **VERIFY + 一次成功**，把恢复预算留给「预接触对齐失败」而不是「终局失败」。**短任务原则**：B 有 17–29，可以承受 2–3 次重抓，优先 REGRASP/REALIGN。

### 7.3 期望收益

恢复：

| q（可恢复失败比例） | r（恢复成功） | s（预算饱和） | Δp（p=0.25） |
|---|---:|---:|---:|
| 0.3 | 0.2 | 0.8 | +3.6pp |
| 0.3 | 0.3 | 0.8 | +5.4pp |
| 0.5 | 0.3 | 0.8 | +9.0pp |
| 0.5 | 0.5 | 0.8 | +15.0pp |
| 0.5 | 0.5 | 1.0 | +18.8pp |

- 目标区间 **+4–8pp**；+15pp 是乐观上界，必须 G4 证明。
- 步骤分 salvage：失败 trial 平均多拿 5–10 分 → 平均 +3.75–7.5 分（tie-break）。
- 人类让行：`ΔS_human = 0.2 Δp_h`；human 轴 +10pp → 全局 +2pp。
- 能量：不直接加分；通过减少 timeout/热降频、把预算留给重试来间接影响成功率。
