# 第 43 轮（本轮循环第 1 轮） · 柔顺对齐证书 CAC：把安全从「状态约束」升级为「能量–意图联合约束」（四层架构 v8）

> 承接第 42 轮 v19（SCV × CKB × ECR 的 Sim-Cert-RAG 飞轮）。第 42 轮自陈最大风险是「仿真偏差累积 + 检索幻觉导致证书在自信中静默失效」。本轮灵感词「柔顺控制」「安全对齐」从两个此前被忽略的维度切进来：**柔顺控制**指出，在接触丰富、人机共处的场景里，「安全」不是把状态关进不变式盒子，而是**约束交互能量与接触力**——停下（SafeStop）在接触中可能比继续柔顺更危险（掉落、夹持失稳、人机对顶）；**安全对齐**指出，前 42 轮所有证书都默认「安全规约是给定的」，但真实人机任务里规约本身是**隐变量**（人想要多快、多硬、多近），证书必须对「意图的不确定性」鲁棒，而不是对一个被写死的 θ 鲁棒。两者合流：**用柔顺提供满足力/能量约束的物理执行权限，用对齐刻画规约本身的不确定性，并让柔顺刚度随对齐置信度自适应**——不确定时更柔顺（更安全、更能退让），确定时更刚硬（更高效）。这把 v19 的「证书飞轮」从单轴（soundness vs 可用性）扩展为双轴（能量安全 × 意图对齐）。

## 0. 直觉与动机

**灵感 1（柔顺控制 → 安全是「能量账本」而非「位置围栏」）**：位置/速度守卫在自由空间很好用，但一旦进入接触（抓取、擦洗、递物、人机握手、被推挤），位置误差与力是耦合的：硬顶会让力发散，急停会让人或物失稳。柔顺控制（阻抗/导纳、能量罐 passivity control、力限幅）的直觉是：把安全写成**能量不等式**——闭环端口哈密顿系统的储能变化不超过外部注入功率，能量罐 E_tank 永不透支，接触力 ‖F‖ ≤ F_max。于是「安全证书」从「x ∈ Safe」变成「(x, E_tank, F) ∈ Safe_energy」。关键好处：**柔顺给自动机提供了第三种动作**——除「前进」和「SafeStop」外还有「让（yield）/顺（comply）」，接触场景下的安全回退不再是停机，而是降低刚度、耗散能量。

**灵感 2（安全对齐 → 规约是隐变量，证书要对意图集鲁棒）**：第 42 轮的 θ、不变式、课程目标都默认「人已经把安全规约写对了」。安全对齐的直觉是：真正的规约是一个**意图后验** b(ω)，ω 是偏好（速度/安全/力的权衡、任务目标、社交距离）。我们不该对一个点估计 ω̂ 认证，而应对一个 **(1−δ) 可信意图集 Ω_δ** 认证：证书必须对 Ω_δ 内所有意图都成立，对齐风险 R_align = sup_{ω∈Ω_δ} violation(Φ_ω)。这正好补上第 42 轮「RAG 检索到不相似模板却高置信合并」的失效链——把「模板适用域」升级为「意图可信集」，合并前检查的不是相似度而是**对齐集覆盖**。

**灵感 3（耦合：柔顺刚度 ← 对齐置信度，形成「对齐-柔顺」反馈）**：本轮真正的火花。**对齐置信度 κ_t 决定柔顺程度**：意图不确定（Ω_δ 大、后验熵高）时，机器人应更柔顺——降低阻抗 K、增大阻尼 D、缩小 F_max，用「物理退让」换取「不违反任何候选意图」；随着人类反馈（纠正、偏好、力上限设定）使 b(ω) 收缩，κ_t 上升，允许提高刚度与速度以提升任务效率。形式化为调度律 K_t = K_min + (K_max−K_min)·g(κ_t)。这条律把「安全对齐」从纯认知层的约束，落成**物理层的刚度旋钮**，也让「柔顺」从被动手艺变成**有认证依据的主动策略**。

**飞轮升级**：v19 是 Sim→RAG→Edge→Sim；v20 在其上叠加一条 **Human→Intent→Alignment→Compliance→Behavior→Human** 的对齐飞轮。两条飞轮共享 CKB 与 ECR：对齐飞轮改的是「规约与刚度」，证书飞轮改的是「有效域与阈值」。最终证书对象同时携带 (C_sim, C_comp, Ω_δ, K_t 调度)，是一个「能量-意图」联合证书。

## 1. 形式化定义（增量：定义 38–45）

**定义 38（柔顺证书与合规包络）**：设闭环为端口哈密顿系统 ẋ = (J−R)∇H + Bu, y = B^T∇H。控制器带阻抗 (K, D)、力限 F_max、能量罐 E_tank。称其**柔顺合规**当且仅当对接触场景集 S 中所有场景：(i) 无源性 dH/dt ≤ y^T u；(ii) 能量罐非负 E_tank(t) = E_tank(0) + ∫(y^T u − ε_diss) ≥ 0；(iii) 力界 ‖F_int‖ ≤ F_max。**合规包络** C_comp = {(K, D, F_max, E_tank(0)) : 上述成立 ∀s∈S}。

**定义 39（意图隐变量与对齐可信集）**：意图 ω ∈ Ω 参数化规约族 Φ_ω（含速度偏好、安全权重、期望接触刚度、社交距离）。人类反馈序列 h_{1:t} 给出后验 b_t(ω)。取 (1−δ) 可信集 Ω_δ,t = {ω : b_t(ω) ≥ τ_δ}（或最高后验密度区）。**对齐鲁棒证书**要求 ∀ω∈Ω_δ,t，行为满足 Φ_ω。

**定义 40（对齐风险与置信度）**：R_align(t) = sup_{ω∈Ω_δ,t} violation(Φ_ω; π)。对齐置信度 κ_t = 1 − |Ω_δ,t|/|Ω|（或用后验熵 H(b_t) 的归一化补），κ_t ∈ [0,1]。

**定义 41（对齐-柔顺调度律）**：K_t = K_min + (K_max−K_min)·g(κ_t)，D_t = 2ζ√(K_t m̂)，F_max,t = F_min + (F_max−F_min)·g(κ_t)，其中 g 单调增、g(0)=0、g(1)=1，并受 C_comp 约束：(K_t,D_t,F_max,t) ∈ C_comp ∀t。**命题**：若 g 连续且 C_comp 凸，则存在 κ* 使调度始终可行；κ_t 下降时系统单调更柔顺（更安全但能力下降）。

**定义 42（接触模式证书自动机 CCA）**：在 CAR 上扩展接触模式 M = {free, impact, contact, grasp, slide}。边 e = (m→m′) 带运动守卫 g_e(x) ≥ θ_e、能量守卫 E_tank − E_int ≥ 0、力守卫 ‖F‖ ≤ F_max。每个模式携带 (C_comp, Ω_δ, K_t)。转移的**联合安全条件**是运动守卫 ∧ 能量守卫 ∧ 对齐守卫（ω∈Ω_δ 下 Φ_ω 不违反）。

**定义 43（能量-对齐联合不变式）**：在乘积空间 (x, E_tank, b) 上定义 Inv = {E_tank(x) − E_int(x) ≥ 0} ∧ {R_align(x; b) ≤ ε_align}。CCA 的所有可达状态须落在 Inv 内。这统一了无源性（能量）与对齐（意图）。

**定义 44（对齐风险的可证有限样本界）**：用 conformal prediction 在人类反馈校准集上构造 Ω_δ,t，使 P(R_align ≤ ε | h_{1:t}) ≥ 1−δ（边际覆盖）。对分布漂移（换人、换任务）用加权 conformal 或自适应 conformal 维持条件覆盖。

**定义 45（双飞轮证书对象）**：证书 Cert = (C_sim, α_e, C_comp, Ω_δ, {K_t 调度}, 版本/溯源)。运行时同时检查：Sim 迁移界（v19）、能量/力界（定义 38）、对齐风险界（定义 44）。任一越界触发对应飞轮：能量越界 → 降刚度/耗散；对齐越界 → 扩大 Ω_δ 并降刚度；Sim 偏移 → 重跑 SCV。

## 2. 产出设计（新增 IP-57/58/59 + 升级既有）

### 2.1 IP-57 COMPLIANCE-CERTIFIED CONTROL（CCC，柔顺证书控制器）
1. **能量罐 passivity 控制**：把阻抗控制嵌入端口哈密顿框架，能量罐记录交互能量；接触时从罐中取能，自由时回充；罐空 → 强制降刚度/进入耗散模式（而非硬停）。
2. **力限幅 + 柔顺回退**：‖F_int‖ 超 F_max 时切换到「让」策略（导纳），而非 SafeStop；给出「柔顺 SafeStop」= 刚度降到 K_min 并保持姿态。
3. **合规包络离线计算**：对 (K,D,F_max) 网格做 passivity/力界验证，得 C_comp 只读表（与 IP-56 L0 表同构），运行时查表选可行阻抗。
4. **刚度-阻尼联合调度**：按定义 41 的 κ_t 调度，输入来自 IP-58。

### 2.2 IP-58 INTENT-ALIGNED SPECIFICATION（IAS，对齐规约引擎）
1. **意图表示**：ω = (速度偏好 v*, 安全权重 λ_s, 接触刚度偏好 K*, 社交距离 d*)，规约族 Φ_ω 用参数化 CBF/代价表示。
2. **人类反馈摄取**：纠正动作、偏好比较（A/B）、显式力上限、语言指令 → 贝叶斯更新 b_t(ω)；语言用 VLM 解析为 ω 上的软约束。
3. **可信集构造与 conformal 校准**：定义 44，输出 Ω_δ,t 与 ε_align；漂移时用自适应 conformal 扩集。
4. **对齐审计**：对 Ω_δ,t 逐意图跑快速可达性/反例检查，输出 R_align 与最坏意图 ω*，供人确认（补 v19 的 RAG 合成审计）。

### 2.3 IP-59 CONTACT-CERTIFIED AUTOMATON（CCA，接触证书自动机）
1. **接触模式识别**：从力/触觉/电流估计接触模式（free/impact/contact/grasp/slide），带置信度。
2. **模式级证书**：每模式一个 (C_comp, Ω_δ, 守卫集)，转移需同时过运动/能量/对齐三重守卫。
3. **模式切换 bumpless transfer**：切换时保证能量罐连续、力连续，避免冲击（impact 模式专门处理瞬时能量注入）。
4. **组合**：接触模式乘积自动机入 CKB（升级 IP-47）。

## 5. 本轮最大风险

**一句话**：对齐可信集 Ω_δ 只给**边际**覆盖，若人的偏好在运行中漂移而 Ω_δ 未及时扩张，机器人会以「高置信的柔顺」违反真实意图；且无源性/能量罐保的是**稳定性**而非**任务可行性**（罐枯竭=功能退化），这两条叠加会制造一种比第 42 轮更隐蔽的「合规却违心」失效。

| κ_t = 1 − |Ω_δ,t|/|Ω| | 对齐置信度 | 后验熵归一化补，驱动柔顺调度 |
| K_t = K_min+(K_max−K_min)g(κ_t) | 刚度调度律 | g 单调增，受 C_comp 约束 |
| Inv = {E_tank−E_int ≥ 0} ∧ {R_align ≤ ε_align} | 能量-对齐联合不变式 | 乘积空间 (x, E_tank, b) 上的安全集 |
| Cert = (C_sim, α_e, C_comp, Ω_δ, {K_t}) | 双飞轮证书对象 | 同时含仿真迁移界、能量界、对齐界 |

## 2. 关键算法（伪代码）

### IP-57 CCC：能量罐柔顺控制与合规包络
```
def compliant_control_step(x, x_des, v, K_t, D_t, F_max, tank):
    # 阻抗控制：期望力 = K_t*(x_des - x) - D_t*v
    F_cmd = K_t * (x_des - x) - D_t * v
    mode = 'contact'
    # 力限幅（导纳式退让，不硬停）
    if norm(F_cmd) > F_max:
        F_cmd = F_max * F_cmd / max(norm(F_cmd), 1e-9)
        mode = 'yield'
    # 端口哈密顿能量核算：注入功率与耗散
    P_inj  = dot(F_cmd, v)
    P_diss = dot(v, D_t * v)
    tank.E += dt * (P_diss - P_inj)      # 接触时取能，自由时回充
    if tank.E <= 0:                       # 能量枯竭 → 单调降刚度，柔顺保持
        K_t, D_t = K_min, D_max
        F_cmd = K_min * (x_des - x) - D_max * v
        tank.E = 0.0
        mode = 'compliant_hold'
    return F_cmd, tank, mode

def check_compliance_envelope(K, D, F_max, C_comp_L0):
    # C_comp_L0: 离线验证过的 (K,D,F_max) 只读表，O(log N)
    return lookup(C_comp_L0, (K, D, F_max))
```

### IP-58 IAS：意图后验、可信集与对齐审计
```
def update_intent_posterior(b, feedback):
    if feedback.type == 'correction':
        b = bayes_update(b, likelihood_correction(feedback))
    elif feedback.type == 'preference':          # Bradley-Terry 偏好
        b = bradley_terry_update(b, feedback.A, feedback.B)
    elif feedback.type == 'force_limit':
        b = truncate(b, lambda w: w.F_max <= feedback.value)
    elif feedback.type == 'language':
        b = soft_constraint(b, vlm_parse(feedback.text))  # 语言仅作软约束
    return normalize(b)

def build_credible_set(b, delta):
    # 最高后验密度 / 阈值集
    return {w: p for w, p in b.items() if p >= tau_delta(b, delta)}

def conformal_align_bound(calib_scores, alpha):
    n = len(calib_scores)
    q = ceil((n + 1) * (1 - alpha)) / n
    return quantile(calib_scores, min(q, 1.0))   # 有限样本边际覆盖

def alignment_guard(x, Omega_delta, eps_align):
    R = max(violation(Phi[w], x) for w in Omega_delta)
    return (R <= eps_align), R, argmax_w(Omega_delta, x)  # 返回最坏意图 ω*
```

### IP-59 CCA + IP-57 调度：三重守卫与变阻抗
```
def schedule_impedance(kappa, C_comp_L0):
    g = monotone_sigmoid(kappa)                  # g(0)=0, g(1)=1
    K = K_min + (K_max - K_min) * g
    D = 2 * zeta * sqrt(K * m_hat)
    F = F_min + (F_max - F_min) * g
    if not check_compliance_envelope(K, D, F, C_comp_L0):
        K, D, F = project_to_envelope(K, D, F, C_comp_L0)  # 保守投影
    return K, D, F

def cca_transition(e, x, tank, Omega_delta):
    if margin_lookup(x) < theta_e: return False          # 运动守卫
    if tank.E - E_int(x) < 0:      return False          # 能量守卫
    ok, R, _ = alignment_guard(x, Omega_delta, eps_align)
    return ok                                            # 对齐守卫

def bumpless_switch(m_from, m_to, tank, F_prev):
    assert tank.E >= 0
    # 力连续 + 能量罐连续，impact 模式单独限幅瞬时能量注入
    return project_force_continuous(F_prev, m_to.F_prev, m_to.is_impact)

def dual_flywheel_monitor(x, F, cert):
    checks = {
        'sim':    margin_lookup(x) >= cert.alpha_e * cert.theta_sim,
        'energy': (cert.tank.E - E_int(x) >= 0) and (norm(F) <= cert.F_max),
        'align':  alignment_guard(x, cert.Omega_delta, cert.eps_align)[0],
    }
    if not checks['energy']: trigger('compliance_flywheel')  # 降刚度/耗散
    if not checks['align']:  trigger('alignment_flywheel')   # 扩 Ω_δ + 降刚度
    if not checks['sim']:    trigger('sim_flywheel')         # SCV 重跑
    return checks
```

## 6. 本轮最大风险

**一句话**：对齐可信集 Ω_δ 只给**边际**覆盖，若人的偏好在运行中漂移而 Ω_δ 未及时扩张，机器人会以「高置信的柔顺」违反真实意图；且无源性/能量罐保的是**稳定性**而非**任务可行性**（罐枯竭=功能退化），这两条叠加会制造一种比第 42 轮更隐蔽的「合规却违心」失效。
