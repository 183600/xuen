# 第 16 轮（研究线累计；本轮灵感循环第 2 轮）· HACI-VLA：人机协作 + 状态隔离 + 多模态交互，把 OOD-G 从不可检测变为可询问

> 检索/复核日期：**2026-11-03（UTC）**。赛事身份不变：宇树 UniBot 世界挑战赛，G1 + Dex1，32 项桌面任务，通才单模型赛道。本轮三个灵感词是「人机协作」「状态隔离」「多模态交互」。**不推倒**第 10-15 轮 FACT-VLA / GEO-RESIDUAL / CHUNK-SERVO / WAVE-SERVO / VOI-MAP / ZEST-VLA；HACI-VLA 是 ZEST-VLA 之上的**协作层**：ZEST 决定「信不信 VLA」，HACI 决定「何时问人、如何融合」。

## 0. 先给直觉：第 15 轮学会了不信任自己，但还没学会求助

第 15 轮 ZEST-VLA 把执行者胜任力建模为可观测残差，用 conformal + CUSUM 做风险受控的信任门，并在 OOD-E / OOD-S 时退回手工几何原语。它清晰划出了边界：

> OOD-G（VLA 与语义地图共享错误先验）不可检测，自监督残差与 ID 不可分。

这正是人机协作的切入点。OOD-G 的本质是** grounding 缺乏外部信源**。透明杯子被误认、颜色未见、空间关系歧义，这些在机器人内部是不可区分的，但在人类那一侧是单目就能分辨的。

直觉是：**把「不可检测」转化为「可询问」**。不去训练第二个检测器，而是把人类作为一个带延迟、带噪声的多模态传感器，在状态隔离的前提下只在需要时接入。状态隔离保证人类输入不会污染自主信念的内部一致性；多模态交互保证查询成本足够低；协作协议保证系统仍是单模型合规、可降级。

一句话押注：

> 第 15 轮用动作-观测残差决定信不信；本轮在 ZEST 之上加一层状态隔离的人机协作门：当信任门失效且域检查不可几何化时，用多模态低成本查询把 OOD-G 显式化，机器人自主信念与人类信念分离更新、受控融合，零样本泛化从「受控降级」升级为「受控求助」。

三个可验证创新点：

1. **状态隔离的人机协作**：机器人自主状态 s^r 与人类辅助状态 s^h 独立演化，仅通过窄接口 I_t 受控交换；不引入第二个学习模型，人类输入只作为显式先验注入。
2. **多模态低成本查询**：语音转写 + 视觉指向 + 注视融合为人类意图分布 p_h(o|h_t)，查询只在熵高/预算紧/信任失效时触发，并带超时与回退。
3. **协作-自主分层调度**：在 VOI-MAP 的动作集上扩展 `ASK / ASSIST / AUTO`，ASK 产生多模态查询，ASSIST 注入人类指定的几何原语，AUTO 保持 ZEST 门控；用风险受控的切换保证 ID 不回归。

三个词怎么落地：

| 词 | 落地 | 不做什么 |
|---|---|---|
| **人机协作** | 协作层 L5，查询协议、超时、回退、人类原语注入；人类仅在 OOD-G/高熵时被动参与 | 不做上环实时遥控；不做持续人类在环；不训练人类行为模型 |
| **状态隔离** | s^r 与 s^h 独立更新，融合只通过阈值门控；人类信念不反向写入 VLA 权重或地图置信度 | 不做端到端联合训练；不让人类输入改写 VLA 内部表征 |
| **多模态交互** | 语音对象名 + 指向 2D→3D + 注视热区，规则融合为 p_h；全部为确定性几何/语言解析 | 不引入大模型做模态融合；不做 test-time 微调 |

## 1. 研究日志：为什么是这一层

### 1.1 第 15 轮留下的三个未付费假设

```text
B1. OOD-G 可被内部信号覆盖：若残差不可检测，就只能 HOLD。
B2. 人类输入即安全：若问人，人类永远给出正确澄清。
B3. 信念可随意混合：自主信念与人类信念可以自由融合。
```

B1 是本轮要付的账。B2 在评测环境不成立：人类也会迟疑、指错、延迟。B3 危险：人类输入若直接改写地图，会破坏 VOI-MAP 的预算与一致性。

### 1.2 三个新判断

1. **协作不是替代，而是边界扩展。** 人机协作的价值不在「让人类做」，而在「把不可检测的 OOD-G 变成可检测的询问」。状态隔离确保协作是可逆的、可审计的。
2. **状态隔离是安全前提。** 自主系统需要内部一致性闭环；人类信号是外部、间歇、噪声的。隔离 + 受控门控保证：人类错误不会级联污染自主信念；自主失效也不会把人类拉入死锁。
3. **多模态交互必须低成本。** 查询贵则系统会过度保守。语音 + 指向几乎零额外硬件成本，且与评测自动 API 兼容：人类输入可离线预录为「模拟查询」。

### 1.3 与第 15 轮的关系

| 层 | 第 15 轮 ZEST-VLA | 第 16 轮 HACI-VLA |
|---|---|---|
| 不确定性 | 胜任力 c_t、OOD-E/S | + grounding 不确定性、人类可信度 |
| 自监督 | 残差三元组 | 保留；人类查询作为外部监督信号 |
| 调度 | TRUST/FALLBACK/HOLD | + ASK/ASSIST；门是硬约束，协作是软扩展 |
| 状态 | 单一自主状态 | 双状态隔离 s^r / s^h + 接口 I_t |
| 零样本 | 系统级降级 | 系统级降级 + 受控求助 |
| 安全 | 只删动作 | 保留；人类注入的原语仍经 WAVE-SERVO |

**保留**：ZEST 的残差、conformal/CUSUM、几何原语语法、VOI-MAP、WAVE-SERVO。
**升级**：从「不信任时退一步」升级到「不信任且不可退时问一步」；从单一信念到双信念隔离。
**剪枝**：不训练多模态融合模型；不让人类输入在线更新 VLA；不做持续遥控。

## 2. 机制草图

### 2.1 双状态隔离

```text
s^r_t = (M_t, b_t, c_t, S_t, φ_t)           # 自主信念
s^h_t = (w_t, p_t, g_t, τ_t)               # 人类多模态观测
I_t = gate(s^r_t, s^h_t) ∈ {NONE, ASK, MERGE}
```

更新规则：

- s^r_{t+1} = f_r(s^r_t, o_t, a_t)  独立
- s^h_{t+1} = f_h(s^h_t, h_{t+1})   独立
- 融合只在 I_t = MERGE 时发生，且满足 τ_merge 条件。

### 2.2 多模态意图解析

语音 w_t → 对象名集合 N_t（规则 NER + 任务词典）。
指向 p_t → 2D 像素 → 射线投射到语义地图 → 候选对象集合 O_p。
注视 g_t → 热区加权。

```text
p_h(o|h_t) ∝ 1[o∈N_t] · 1[o∈O_p] · exp(-||proj(o)-g_t||/σ)
```

无学习，仅几何与词典。

### 2.3 协作触发

```text
trigger_ASK = (mode= FAL LBACK ∧ dom≠geometric) ∨
              (H[b_t] > H_thr ∧ B_t < B_thr) ∨
              (c_t < c_thr ∧ S_t > h)
```

触发后：发出多模态查询，等待 T_wait。超时则回退到 HOLD/VLA。

ASSIST：人类返回对象 id 或原语选择，直接注入 primitive_queue，优先级高于 VLA，但仍经域检查与 WAVE-SERVO。

### 2.4 早期中止与成本

查询成本 c_q 远小于盲目执行 30 步坏计划。人类查询一次最多 1-2 秒，评测可离线模拟。

## 3. 可证伪假设

| 编号 | 假设 | 证伪条件 |
|---|---|---|
| H1 | 状态隔离下，人类错误不会导致 ID 成功率回归 >2pp | ID 回归 >2pp |
| H2 | 多模态查询在 OOD-G 上将成功率提升 ≥8pp，且查询率 ≤15% | 提升 <5pp 或查询率 >30% |
| H3 | 隔离融合优于直接混合（无隔离基线） | 无隔离不劣于隔离 |
| H4 | 查询延迟 ≤2s 时对总时长影响 ≤5% | 延迟导致超时率上升 >5% |

## 4. 什么情况下放弃

- 人类查询率 >30% 或 ID 回归 >2pp → 协作过侵入，退回 ZEST-only。
- 多模态解析准确率 <70% → 查询噪声过大，关闭 ASK 仅保留 ASSIST 白名单。
- 并发 32 任务下查询风暴导致 p99 >200ms → 查询降采样或离线批处理。

## 5. 一句话押注

第 15 轮让系统学会不信任自己；本轮让系统学会在状态隔离下安全地求助，用多模态低成本查询把不可检测的 OOD-G 显式化，使零样本失败从「受控降级」变为「受控求助」。

## 6. 本轮最大的风险

**人类输入的语义对齐错误**：如果语音对象名与地图标签不一致，或指向解析偏差，人类意图分布 p_h 会错误地「确认」一个错误的 grounding，导致系统在隔离门控打开后仍执行错误目标，且错误难以被残差检测，因为人类输入被视为可信先验。状态隔离只能防止污染扩散，不能防止一次错误的融合。

# 第 16 轮产物 · HACI-VLA 技术报告：人机协作 + 状态隔离 + 多模态交互

> 检索/复核日期：**2026-11-03（UTC）**。对象：宇树 UniBot 世界挑战赛，G1+Dex1，32 项桌面任务，通才单模型赛道。本报告是研究线累计第 16 轮、灵感循环第 2 轮「人机协作 / 状态隔离 / 多模态交互」的工程化产物。它在第 15 轮 ZEST-VLA 之上加一层协作层 L5，不替换 FACT-VLA / GEO-RESIDUAL / CHUNK-SERVO / WAVE-SERVO / VOI-MAP / ZEST。

## 0. 结论与边界

### 0.1 一句话结论

ZEST-VLA 能在 OOD-E/S 时受控降级，但对 OOD-G 无能为力；HACI-VLA 在保持状态隔离的前提下，用多模态低成本查询把 OOD-G 显式化，在信任门失效时触发 ASK/ASSIST，人类意图以独立信念 s^h 存在、仅在门控通过时受控融合，实现零样本失败从「受控降级」到「受控求助」。

### 0.2 本轮不做什么

- 不训练多模态融合模型；融合为规则几何+词典。
- 不在线更新 VLA 权重；人类输入不写入 θ。
- 不做持续遥控；人类参与为事件驱动查询。
- 不假设人类永远正确；人类可信度 h_conf 在线估计并门控。
- 不解决人类自身的语义对齐错误；这是最大风险边界。

## 1. 承接与分层

```
L5 HACI-VLA 协作层（本轮新增）
   双状态隔离 s^r / s^h + 多模态解析 + ASK/ASSIST 门控
L4 ZEST-VLA 胜任力层（第15轮）
   残差 → conformal/CUSUM → TRUST/FALLBACK
L3 VOI-MAP 元认知层（第14轮）
L2 WAVE-SERVO 控制层（第13轮）
L1 VLA server 冻结模型
```

协作层只读 L4 的 mode 和 c_t，只写允许动作集的扩展，不改动执行通路。

## 2. 符号与形式化

### 2.1 双状态

自主状态： s^r_t = (M_t, b_t, c_t, S_t, φ_t, B_t)
人类状态： s^h_t = (w_t, p_t, g_t, t_last, h_conf_t)

接口： I_t ∈ {NONE, ASK, MERGE}

更新：

s^r_{t+1} = f_r(s^r_t, o_t, a_t)
s^h_{t+1} = f_h(s^h_t, h_{t+1})

融合仅在 I_t=MERGE 时：

b^{fuse}_t ∝ b_t^{λ} · p_h(o|h_t)^{1-λ},  λ = σ(α·c_t + β·h_conf_t)

### 2.2 多模态意图解析

语音 w_t → N_t = NER(w_t) ∩ TaskVocab
指向 p_t → 2D 坐标 → 射线投射 → O_p = {o | dist(ray(o), p_t) < ε}
注视 g_t → 热区权重 w_g(o)

p_h(o|h_t) = Z^{-1} · 1[o∈N_t]·1[o∈O_p]·exp(-||proj(o)-g_t||/σ_g)

全部确定性，无学习。

### 2.3 协作触发与动作集

允许动作集扩展：

AUTO: {SERVO, LOOK, VLA, COMMIT}
FALLBACK: {FALLBACK, LOOK, VLA, HOLD}
ASK: {ASK, LOOK, VLA, HOLD}
ASSIST: {FALLBACK_human, LOOK, VLA, HOLD}

触发条件：

trigger_ASK = [mode=FALLBACK ∧ dom≠geometric] ∨ [H[b_t] > H_thr ∧ B_t < B_thr] ∨ [c_t < c_thr ∧ S_t > h]

trigger_ASSIST = human_response received ∧ h_conf_t > τ_conf ∧ dom=geometric

超时：T_wait = 2s，超时则 I_t←NONE，回退 HOLD。

## 3. 算法

### 3.1 主循环伪代码

```python
class HacIPolicy:
    def __init__(self):
        self.zest = ZestPolicy()
        self.s_r = init_robot_state()
        self.s_h = init_human_state()
        self.query_timer = 0

    def get_action(self, obs, human_msg=None):
        update s_r via zest + VOI-MAP
        update s_h via human_msg
        I = self.decide_interface(s_r, s_h)
        if I == ASK:
            emit_query(s_r, s_h)
            return HOLD
        if I == MERGE:
            b_fuse = fuse(s_r.b, s_h)
            s_r.b = b_fuse
        act = self.zest.select_action(obs) # 受 I 约束
        return execute(act)
```

### 3.2 接口决策伪代码

```python
def decide_interface(s_r, s_h):
    if s_r.mode == FALLBACK and domain_check != geometric:
        return ASK
    if entropy(s_r.b) > H_thr and s_r.B < B_thr:
        return ASK
    if s_h.conf > tau and s_h.t_last < T_stale:
        return MERGE
    return NONE
```

### 3.3 状态隔离不变式

Invariant 1: s_r 更新不依赖 s_h 以外接口。
Invariant 2: s_h 更新不依赖 s_r。
Invariant 3: 融合仅在 I=MERGE 且 h_conf>c_thr 时单向写入 b_t。

## 4. 性质、复杂度、正确性

### 4.1 隔离性

命题1（无污染）：在 I=NONE 时，∂s^r_{t+k}/∂s^h_t = 0 对所有 k>0。

证明：更新函数 f_r 不读取 s^h；接口只在 I≠NONE 时激活。∎

### 4.2 安全降级

命题2（动作集单调）：HACI 的动作集 ⊆ ZEST 的动作集 ∪ {ASK,HOLD}。所有执行仍经 WAVE-SERVO。

### 4.3 复杂度

多模态解析 O(|O|) ≤ 100 对象；射线投射 O(P)。总体 <0.5ms/块。
内存增加 O(|O| + W_h) < 5MB。

### 4.4 正确性边界

人类查询不能保证 OOD-G 解决；若 p_h 与真实目标不匹配，融合会引入错误。隔离保证错误不会扩散到自主闭环，但单次融合错误仍可能导致失败。

## 5. 实验设计

G13：多模态解析准确率 ≥85% 在合成指向/语音上。
G14：OOD-G 任务上查询后成功率 +8pp，查询率 ≤15%。
G15：ID 任务上人类介入率 ≤5%，成功率回归 ≤2pp。
G16：状态隔离不变式通过审计日志验证。

## 6. 风险

- 人类延迟导致超时。
- 语音/指向解析错误导致误融合。
- 查询风暴导致 p99 上升。

## 7. 一句话押注

用状态隔离把人类作为外部多模态传感器，在 ZEST 信任门失效时以低成本查询把不可检测的 OOD-G 显式化，实现受控求助而非盲目降级。

## 8. 本轮最大的风险

人类意图解析的语义对齐错误会让系统在隔离门控打开后仍融合错误先验，导致一次错误的求助把错误目标「确认」下来，且该错误无法被残差检测，因为人类输入被视为可信外部信源；状态隔离只能限制污染范围，不能防止单次错误的融合。
