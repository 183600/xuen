# 第 47 轮（新循环第 1 轮） · Humanoid-Middleware：浮动基座下的端到端时效证书与步态-安全协同（四层架构 v11）

> 承接第 46 轮 v10/v23 的 Energy-Context-Depth × Memory-Safety-Voice。v23 已把姿态、能量、记忆、语音安全串成闭环，但仍隐含假设 **H5：证书的签发者与消费者共享同一个可信、同步、无丢包的计算基座，且机器人是固定基座**。本轮两个灵感词精确命中 H5：**人形机器人**使基座浮动、证书半径随步态时变、安全谓词从"末端位姿"扩展为"全身平衡 + 接触"；**中间件**使证书在 DDS/ROS 2 上经历延迟、丢包、乱序、时钟跳变与 QoS 静默降级。二者耦合出的新问题是：**当证书跨越一条多速率、可能失同步的中间件到达全身控制器时，如何保证端到端（issue→consume→act）的 soundness，并在时效预算收缩时用步态而非停机来换取时间。**

## 0. 直觉与动机

**灵感 1（人形机器人 → 证书的时变半径与全身约束）**
直觉：固定基座机器人的相机位姿只取决于标定；人形机器人的相机挂在头部链、末端挂在臂链，二者都通过浮动基座耦合到 IMU 与足底接触。站立时的证书半径、行走时的振动放大、上下楼时的接触不确定性完全不是一个量级。更关键的是：**步态速度决定证书所需的更新频率**——走得越快，同样的感知延迟对应的位置外推误差越大，证书的允许寿命就越短。于是"走多快"不再是纯运动规划问题，而是证书预算的一部分：**步态是可被安全层调用的时间预算旋钮**。

**灵感 2（中间件 → 证书的生命周期与传输契约）**
直觉：一份数学上正确的证书，如果在 DDS 队列里躺了 120ms 才被消费，它已经不代表当前状态。ROS 2 的 QoS 策略（best-effort / reliable / keep-last-depth）会在拥塞时静默丢弃或覆盖旧消息；时间戳依赖 PTP 同步，节点重启会让时钟跳变；控制、感知、证书三条链路速率不同，天然产生队列老化。因此证书不能只是一段区间，必须携带 **传输契约**：签发时刻、有效期、因果依赖、步态模式标签、QoS 等级、冗余路径。中间件必须从"透明管道"升级为**可信执行边界**：消费前校验，不满足即 fail-closed。

**灵感 3（耦合 → 用步态换新鲜度，而非用停机换安全）**
直觉：当中间件抖动上升、或电池迫使降低感知频率时，最保守的做法是立刻停机；但人形机器人停机本身也可能不稳（单脚支撑、斜坡）。更好的策略是**降速或切换到更稳的步态**：速度下降使位置外推误差增长率下降，从而允许更长的证书有效期，重新满足端到端预算。这形成一条 speed–freshness frontier：在给定中间件健康度与平衡裕度下，存在一个最大可行速度 s*；低于它可安全执行，高于它必须降级。安全层于是同时调节三件事：模态 m_t、步态 λ_t、速度 s_t。

**耦合升级**：在 v10 四层架构上新增 **端到端时效层**。WBPC 负责签发全身证书，CTC 负责把证书及其传输契约安全送达，GAC 负责在时效不满足时调整步态/速度或 fail-closed。四层 v11：根信任层增加**传输租约 ℓ_mw**（与姿态租约 ℓ_p、能量租约 ℓ_e 并列）；L1 几何层由固定基座 PSE 升级为浮动基座全身证书；L2 上下文/记忆层把步态意图与中间件健康度纳入检索键；L3 CAR 守卫加入全身不变量与新鲜度门；L4 DCL 采集中间件轨迹与步态压力样本。

## 1. 形式化定义（增量：定义 59–63）

**定义 59（浮动基座全身证书 WBPC）**
设步态模式 λ∈Λ={stand, walk, stair, recover}，基座状态 x_b=(p_b,R_b,v_b)，关节角 q，接触集合 C。证书为三元组
P_t^wb=(P_t^base, P_t^cam, P_t^ee)，由运动学复合
P_t^cam = FK_cam(P_t^base, q)，P_t^ee = FK_ee(P_t^base, q)。
半径（单边共形校准）
r(λ,C)=r_0(λ)+L_v(λ)‖v_b‖Δt+L_q σ_q+L_c σ_contact(C)+L_ω rad(P_t^{ω})。
**soundness**：P(X_t^wb ∈ P_t^wb | λ, ℓ_p 有效) ≥ 1−α_wb。

**定义 60（证书年龄与消费时有效性）**
签发时刻 τ_issue，消费时刻 t，证书年龄
AoC(t)=t−τ_issue。
给定步态 λ 的有效期 V(λ,φ)（由共形校准与运动外推误差共同决定）。证书在消费时有效当且仅当
AoC(t) ≤ V(λ,φ) 且所有因果依赖（传感器帧、能量租约、模式标签）在 t 时刻仍有效。
**关键区分**：签发时 sound ≠ 消费时 sound；中间件可能把一份"曾经正确"的证书变成"现在错误"的证书。

**定义 61（证书传输契约 CTC）**
传输租约 ℓ_mw=(topic, qos, D(λ), ε_drop, B_clock, k_red)，其中 D(λ) 为模式相关截止期，B_clock 为允许时钟偏差，k_red 为冗余路径数。
**契约满足**当且仅当
P(AoC(t_consume) ≤ V(λ,φ) ∧ delivered ≤ D(λ)) ≥ 1−ε_mw
且 |t_local−t_issue| ≤ B_clock。
**新鲜度预算不等式**（设计约束）：
V(λ) ≥ D(λ) + B_clock + J_{99} + T_react，
其中 J_{99} 为中间件 99 分位抖动，T_react 为安全反应时间。任一时刻不等式被破坏，消费者必须拒绝执行。

**定义 62（全身安全不变量）**
动作 a_t 可执行当且仅当
G(P_t^wb, C_t) = min{ ZMP/CoM 支撑多边形裕度, 接触力锥裕度, 关节限位裕度 } ≥ 0
且 B(v_t, P_t^ee, ω_t) ≥ θ_safe（沿用 IP-68 指令-姿态绑定），且 ℓ_e、ℓ_mw 同时有效。
**注意**：固定基座时代 G 可忽略；人形机器人上 G 与 P_t^ee 是同一安全问题的两面，不能分开认证。

**定义 63（步态-证书调度 GAC）**
在模式-速度对 (λ,s) 上求解
max_{λ,s} E[progress | λ,s]
s.t. P(cert sound ∧ delivered | λ,s) ≥ 1−α_total，
     G(λ,s) ≥ 0，E(t+Δ|m,λ) ≥ E_min，V(λ,s) ≥ D(λ)+B_clock+J_{99}+T_react。
**速度-新鲜度前沿**：s*(λ)=max{s : 新鲜度预算不等式成立}。若 s*>0 则降速到 s* 仍可执行；若 s*=0（连站立也不满足）才允许全局 fail-closed。GAC 的输出同时是运动指令与安全状态。

## 2. 三大新增产出与既有 IP 升级

**IP-69 WBPC（Whole-Body Pose Certificate）**
- 浮动基座 + 运动链复合：base→cam / base→ee 的区间运动学传播
- 步态条件化半径：为 stand/walk/stair 分别做单边共形校准
- 接触/IMU 融合：用足底接触事件与 IMU 修正外推增长率 L_v(λ)
- 模式标签与 epoch：证书携带 λ 与模式切换代数，防止消费者误用旧模式证书

**IP-70 CTC（Certificate Transport Contract）/ CFM 认证新鲜度中间件**
- 证书信封：{payload, issue_t, validity, deps, λ, epoch, sign, qos_class}
- 消费门：年龄、时钟偏差、模式匹配、依赖有效、签名链、预算不等式六重校验
- QoS 契约选择：按 λ 选择 reliable/best-effort/冗余 k_red，并显式测定 ε_drop、J_99
- 传输租约：把"能否按时送达"从祈祷变成可度量、可失效的契约

**IP-71 GAC（Gait-Aware Certificate Governor）**
- 速度-新鲜度前沿估计：给定中间件健康度与平衡裕度求 s*(λ)
- 步态降级阶梯：walk→slow-walk→stand→freeze，每级重算 V、D、G
- liveness 守卫：禁止"为满足证书永不移动"，设置最小任务进度与冻结超时告警
- 与能量租约联动：冗余通道与高频证书的带宽/功耗计入 ℓ_e

**既有 IP 升级**
IP-63 ECPS：模态决策额外受 D(λ) 与冗余带宽成本约束
IP-68 SAB：绑定函数从末端扩展到全身 G(P_t^wb, C_t)
IP-61 DCL：采集中间件延迟/丢包/时钟偏差轨迹与步态压力样本
IP-62 CCA：新增中间件红队（延迟注入、重放、QoS 降级、分区、时钟跳变、模式混淆）
IP-51 CAR：守卫加入 ℓ_mw 有效性与新鲜度预算不等式
IP-45 总线：新增 wb-cert / transport-lease / gait-decision / middleware-health 话题

## 3. 算法骨架

GAC/CTC 每控制周期：
1. 读步态 λ、速度 s、IMU/接触、能量租约 ℓ_e、中间件健康度（p99 延迟、丢包、时钟偏差）
2. WBPC 签发 P_t^wb 并附带 deps、λ、epoch
3. CTC 按 λ 选择 QoS/冗余并发布，同时更新 ℓ_mw
4. 消费者侧六重门校验；失败则回报 FAIL_{stale,clock,mode,dep,auth,budget}
5. GAC 若收到失败或预测 J_99 上升，则降速/降步态重求解 (λ,s)
6. 若连 (stand,0) 都不满足，或 ℓ_p/ℓ_e/ℓ_mw 任一失效 → fail-closed

## 4. 本轮最大风险

**一句话**：把端到端安全寄托在中间件的时效契约上，一旦 DDS QoS 配置错误、PTP 失同步或遭遇延迟/重放注入，过期或错模式的全身证书会被当作有效消费而静默破坏 soundness；反之若为覆盖最坏抖动而过度放大证书半径并持续降速，人形机器人可能陷入"为了安全而永远不敢走"的 liveness 失败，因此必须同时做传输契约的启动自检与在线红队，并把降速策略限制在有下界任务进度的可行域内。

## 2. 关键算法 伪代码

### IP-69 WBPC
```
def wb_certificate(q, x_b, v_b, contact, lam, omega, calib):
    T_cam = fk_chain('base->cam', q)
    T_ee  = fk_chain('base->ee',  q)
    # 单边共形校准得到各模式基础半径与增长率
    r0  = calib.r0[lam]
    Lv  = calib.Lv[lam]
    r_b = r0 + Lv * norm(v_b) * DT + calib.Lq * sigma_q \
             + calib.Lc * sigma_contact(contact) \
             + calib.Lw * radius_from_layer(omega)
    P_b = ellipsoid(x_b.p, r_b, R=x_b.R, axes=calib.axes[lam])
    P_c = propagate_interval(P_b, T_cam, sigma_q, calib)
    P_e = propagate_interval(P_b, T_ee,  sigma_q, calib)
    return {
        'base': P_b, 'cam': P_c, 'ee': P_e,
        'radius': r_b, 'lam': lam, 'epoch': calib.mode_epoch[lam],
        'deps': collect_deps(q, contact, omega, x_b)
    }
```

### IP-70 CTC 发布与消费门
```
def publish_cert(cert, lam, health, energy_lease):
    qos  = QoS_PROFILE[lam]                 # reliability/deadline/keep_last
    k    = 1 if health.p99 < D[lam]/2 else 2  # 抖动大则双路冗余
    if not energy_lease.can_afford(qos, k):
        return False
    env = {
        **cert,
        'issue_t': clock.now(),
        'validity': V[lam],
        'qos_class': qos,
        'sig': sign(cert, node_key)
    }
    for i in range(k):
        bus.publish('wb-cert', env, qos=qos, path=i)
    return True

def consume_gate(env, now, lam_now, health, eps_mw):
    age = now - env['issue_t']
    if abs(now - env['issue_t']) > B_clock:      return 'FAIL_CLOCK'
    if env['lam'] != lam_now:                    return 'FAIL_MODE'
    if env['epoch'] != mode_epoch[lam_now]:      return 'FAIL_EPOCH'
    if age > env['validity']:                    return 'FAIL_STALE'
    if not deps_valid(env['deps'], now):         return 'FAIL_DEP'
    if not verify_chain(env['sig'], env['deps']):return 'FAIL_AUTH'
    if age + health.J99 + T_react > env['validity']:
                                                 return 'FAIL_BUDGET'
    return 'OK'
```

### IP-71 GAC
```
def gait_governor(lam_des, s_des, health, balance, energy, cert_ok):
    ladder = [lam_des, 'slow-walk', 'stand', 'freeze']
    for lam in ladder_from(lam_des):
        s = s_des if lam == lam_des else slow_speed[lam]
        while s >= 0:
            V_eff = V[lam]                    # 可由在线保守化收缩
            D_eff = D[lam]
            if (V_eff >= D_eff + B_clock + health.J99 + T_react
                and balance.margin(lam, s) >= 0
                and energy.feasible(lam, s)
                and cert_ok(lam, s)):
                return lam, s, 'OK'
            s -= DS
    return 'freeze', 0.0, 'FAIL_CLOSED'

def global_control(state):
    cert = wb_certificate(state.q, state.x_b, state.v_b,
                          state.contact, state.lam, state.omega, calib)
    if not publish_cert(cert, state.lam, state.health, state.energy):
        lam, s, st = gait_governor(state.lam, 0.0, state.health,
                                   state.balance, state.energy,
                                   lambda l, sp: False)
        return lam, s, st
    gate = consume_gate(last_env, clock.now(), state.lam,
                        state.health, eps_mw)
    if gate != 'OK':
        lam, s, st = gait_governor(state.lam, state.v_des, state.health,
                                   state.balance, state.energy,
                                   lambda l, sp: gate_ok_after(l, sp))
        return lam, s, st
    return state.lam, state.v_des, gate
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| WBPC 运动链复合 | O(depth(chain)) 每周期 | O(1) | 区间传播 + 单边共形 ⇒ 经验覆盖率 ≥ 1−α_wb |
| CTC 发布 | O(k) | O(1) | 每路径独立 QoS；k 冗余提升送达概率 |
| CTC 消费门 | O(|deps|) | O(1) | 六重校验全部通过才允许消费 |
| GAC 前沿求解 | O(|Λ|·S/ΔS) | O(1) | 在离散步长内单调降速，必达可行点或 freeze |

**端到端 soundness 定理**：设 (i) WBPC 单次签发覆盖率 P(X^wb∈P^wb|λ,ℓ_p) ≥ 1−α_wb；(ii) 传输契约为 P(AoC≤V ∧ delivered≤D) ≥ 1−ε_mw；(iii) 时钟偏差以概率 ≥ 1−ε_clock 不超过 B_clock；(iv) 消费门严格拒绝任何 age>V、模式不匹配或依赖失效的证书。则消费者执行动作的违例概率满足
P(violation) ≤ α_wb + ε_mw + ε_clock。
证明要点：违例只能来自"证书本身错误"、"正确证书未按时送达/被拒后误用"、"时钟越界导致年龄误判"三类互斥事件；消费门把第 (iv) 条的误用概率压到 0，故三者并集由 union bound 控制。∎

**liveness 引理**：若存在 (λ,s) 使新鲜度预算不等式、G≥0、能量约束同时成立，则 GAC 的有限降级阶梯必在 |Λ|·S/ΔS 步内返回 OK；否则返回 freeze 并触发告警，而不是无限等待。

**单调性**：在固定 λ 下，r(λ,C) 随 s 单调增、V(λ) 随 s 单调减，故 s*(λ) 存在且可用二分/离散扫描求得；这给出"降速一定改善时效预算"的形式依据。

## 4. 实验设计 E115–E120

| 实验 | 指标 | 门槛 |
|---|---|---|
| E115 全身证书覆盖率 | stand/walk/stair 实测覆盖率；平均半径 | 覆盖率 ≥ 95%（每模式）；半径 ≤ 固定基座基线 1.5× |
| E116 中间件时效 | p99 延迟、丢包率、门拒绝率、过期消费次数 | p99 ≤ D(λ)；过期消费 0 次；门拒绝可解释率 100% |
| E117 故障注入 | 时钟跳变 ±50ms、节点重启、DDS 分区、QoS 降级、重放 | fail-closed 率 100%；误冻结 ≤ 0.5% |
| E118 步态-新鲜度前沿 | s*(λ) 曲线；可行速度区；任务进度 | walk s* ≥ 0.3 m/s；前沿预测误差 ≤ 10% |
| E119 全身安全 | ZMP/接触锥裕度；跌倒次数；SAB 安全率 | 100h 跌倒 0 次；G<0 时执行次数 0 |
| E120 100h 端到端闭环 | 端到端违例、任务完成率、冻结时长 | 违例 0；任务完成 ≥ 95%；单次冻结 ≤ 2s |

**回退策略**：E116 p99 超 D(λ) → 提高 k_red 或缩短 V(λ) 并降速；E117 误冻结 > 0.5% → 增加冗余通道与启动自检，禁止仅靠放大半径；E118 s* < 0.1 m/s → 切换到 stand-and-reach 任务模式并上报运维；E119 任一 G<0 执行 → 立即回退到 v23 固定基座保守策略。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| DDS QoS 配置错误导致静默丢包/积压 | 高 | 启动自检 + 签名 QoS profile + 消费门强制校验 |
| PTP 失同步或节点重启导致年龄误判 | 高 | 单调时钟为主、墙上时钟为辅；偏差超 B_clock 直接拒绝 |
| WBPC 半径过保守导致频繁冻结 | 高 | 单边共形校准 + 在线收缩 + liveness 守卫与进度下界 |
| 模式标签/epoch 不一致导致错证书消费 | 中 | 证书携带 λ 与 epoch；切换时 epoch 自增并广播 |
| 冗余通道带宽/功耗挤占能量租约 | 中 | k_red 与证书频率计入 ℓ_e；能量紧张时先降 k 再降速 |
| 中间件红队样本污染记忆库 | 低 | 故障注入样本单独审计，不进入正常记忆检索 |

## 6. 本轮最大风险

**一句话**：端到端安全被压缩成一条中间件时效契约，若 QoS 配置、时钟同步或签名链任一环节被错误配置或被延迟/重放攻击绕过，过期或错模式的全身证书会被当作有效输入而静默破坏 soundness；而若为覆盖最坏抖动一味放大证书半径并降速，则会把人形机器人推向"永远不敢走"的 liveness 失败，因此必须把传输契约做成可自检、可红队、可在线失效的根信任之一，并把降速限制在有最小任务进度下界的可行域内。
