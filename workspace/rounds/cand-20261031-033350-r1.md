# 第 13 轮（新灵感循环第 1 轮）· GRASP-SWARM：先把最初 3 秒抓对，再把最后 3 厘米插准

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新灵感循环第 1 轮，三个词是「群体智能」「因果推理」「抓取位姿估计」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是在它们前面加一层：**第 12 轮解决“最后 3 厘米”的开环执行，本轮解决“最初 3 秒”的任务兼容抓取位姿。**

## 0. 先给结论：抓取不是“拿起一个物体”，而是“为后续任务选一个正确的抓法”

先说本轮搜索到的三个变化：

1. **官网榜单页现在显示“即将发布 / Coming Soon”**（2026-10-31 复核），首页、`leaderboard.html`、`runs.html` 都是空表；但 `leaderboard_data.json` 仍然返回 8 个模型的旧预览数据，MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%。上一轮已经证明这份 JSON 是 `gen_leaderboard.py` 生成的预览：`step ≈ k_model × success` 的 R² > 0.999999，32 维任务成功率两两平均相关只有 0.098，且出现 27.29% 这种 10 次 trial 不可能出现的成功率。**所以“榜首不到 30%”可以当难度信号，不能当当前官方榜单，更不能当失败分布。**
2. **官网任务页仍写 32 任务、32000 episodes、169 小时**；HF 合集逐数据集 `meta/info.json` 合计仍是 **33,276 episodes / 18,282,246 frames / 169.28 h**。官网取整到 32k，研究用 33,276。
3. **提交 API 没有变化**：四路 RGB、无 depth/force/tactile、`action_chunk_size` 固定、chunk 内不看新图、选手自部署、N 端口从 8765 起、单模型。`unibot_submission` 仓库最后一次提交仍是 2026-08-21；`unifolm-wla` 最后一次提交是 2026-09-29（LoRA 微调）。

我的判断是：**30% 以下不是一个“模型不够大”的问题，而是两个几何瓶颈叠加**：

- **第一个瓶颈在最初 3 秒**：抓取位姿选错，后面所有 VLA 推理都白费。抓取不是“抓稳”，而是“为后续插入/挂/拉链/拧/放选一个任务兼容的抓法”。
- **第二个瓶颈在最后 3 厘米**：第 12 轮已经论证，30 步开环 chunk 在接触段不反应；用 5 步视觉伺服补最后 3 厘米。

本轮把第一个瓶颈拆开，用一个可落地的组合：

> **从 33k 条成功演示里挖出“任务-阶段-手别”条件化的抓取位姿场（Grasp Pose Field, GPF）；离线用群体优化（PSO）选出少量鲁棒抓取模式；在线用粒子群/粒子滤波做 6D 抓取位姿共识；用因果干预校准的风险表做模式门控与失败归因；选中的抓取目标直接交给 CHUNK-SERVO 的 5 步闭环执行。**

一句话：**把“抓取位姿”从 VLA 的隐式输出，变成一个可检索、可干预、可共识的显式控制变量。**

### 0.1 本轮新增的硬证据：抓取位姿在 base 系里根本不是一个常数

我下载了 HF 数据集前两个任务的首个 parquet 分片（2026-10-31，`G1_Dex1_HangCup` 与 `G1_Dex1_PlugInEthernet`，各约 100 MB），只取 `gripper`、`ee_pose_gripper_base`、`timestamp`、`episode_index` 列，用“夹爪从 >4.0 闭合到 <1.0”检测抓取事件。结果：

| 任务 | 分片 episodes | 抓取事件/ episode | 手别 | 首次闭合中位时刻 | 闭合后开口中位数 | 抓取位姿 base 系 std (x,y,z) | 姿态 std (r,p,y) |
|---|---:|---|---|---:|---:|---|---|
| HangCup | 719 | 1 次：716；2 次：3；0 次：0 | 右手 716 / 左手 3 | 2.20 s | 0.83 / 5.5 | **5.1, 7.1, 2.1 cm** | 0.175, 0.126, **0.364 rad** |
| PlugInEthernet | 211 | 2 次：211；0/1 次：0 | 右手先、左手后：211 | 右手 2.77 s；左手 5.80 s | 0.88–0.89 / 5.5 | 左手 2.4, 3.1, 0.5 cm；右手 3.7, 4.2, 0.6 cm | 右手 yaw std **0.412 rad** |

三个直接推论：

1. **固定 base 系抓取位姿不可行。** HangCup 的抓取点在 x 方向 5%–95% 分位跨 17.5 cm、y 方向跨 21.8 cm、yaw 跨约 42°。这不是“同一抓法的抖动”，而是物体位置/朝向本身就变了；任何“记住一个绝对位姿”的做法都会在位置泛化轴上直接失效。
2. **手别和双手时序是任务语义的一部分。** HangCup 几乎全是右手；PlugInEthernet 211/211 是“右手先抓、左手后抓”，两次闭合中位相隔约 3 秒。一个通才模型如果选错手或顺序，后面再准也没用。
3. **抓取发生在任务很早的阶段。** HangCup 中位 2.2 s / 5.8 s；PlugInEthernet 右手 2.8 s / 19.1 s。最初 3 秒的错误会被 180 秒的 episode 放大成 0 分。

这不是“再训一个抓取模型”的理由，而是“把演示里的成功抓取挖出来，做成一个离线索引 + 在线确定性估计器”的理由。**单模型规则不允许第二个学习策略在线跑；但允许一个由演示索引、几何、控制和因果表组成的确定性抓取层。**

### 0.2 三个灵感词怎么落地

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **抓取位姿估计** | GPF-33K：从成功演示抽 `T_anchor_ee`（物体/受器→夹爪相对位姿）、接近方向、手别、闭合宽度/时机；在线用头双目 + 腕部 RGB 检索/对齐 | 不训第二个 6D 抓取网络；不假设有 depth；不优化“抓稳”而忽略“任务兼容” |

## 1. 本轮核实的事实（只列会改变方案的）

### 1.1 赛事身份：没有更可能的其他 UniBot

搜索会同时命中 **Unibots UK**（英国大学生自主机器人赛，收集乒乓球/钢珠）和 **Unibotics**（JdeRobot 的在线机器人编程挑战）。两者都不是“G1 + Dex1 + 32 桌面任务 + 单模型 + 远程 API”的赛事。按用户描述，最匹配的仍是 **宇树 UniBot 世界挑战赛**；下文全部按它展开。

### 1.2 规则没变，但“单模型”要按最宽解释准备

参赛手册（2026-10-31 通过 `r.jina.ai` 复核，抓到 §1.1–§2.2）仍明确：

- 所有任务须基于**同一模型**完成，不得混合多个模型一起测试；模型类型不限（World Model、VLA 均可）。
- 32 个任务，每个 10 次独立运行；5 类泛化各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
- 单次真机上限 **180 s**；先比 32 任务总平均成功率，再比总平均步骤分，再比更早提交。
- 评测跨 **N 台机器人**；提交从 **8765** 起暴露 N 个连续端口；每端口独立，`reset()` 状态必须隔离。
- 另有**不计分的单任务测试通道**。

**对 GRASP-SWARM 的约束**：抓取层必须每端口独立、CPU 轻量、不加载第二个学习策略；GPF 索引和风险表是静态资产，可以在端口间只读共享，但**不能共享在线 episode 状态**。

### 1.3 榜单：现在没有“实时榜单”，只有旧预览

2026-10-31 复核：

- `https://unibot.unitree.com/`、`leaderboard.html`、`runs.html` 都显示“即将发布 / Coming Soon”。
- `https://unibot.unitree.com/leaderboard_data.json` 仍返回 8 个模型，`generated_from: "gen_leaderboard.py"`。
- 旧预览的头部：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、PI-0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。

**结论**：本轮不从这份 JSON 里挖“哪个任务难”，只用它证明“头部也没解决 70% 的失败”。真实的失败阶段分布，必须用单任务通道自己测（G0/G6）。

- 腕部相机**没有内参矩阵**，只有 `color/ir1/ir2`；在线用腕部做 2D 对齐前必须一次性棋盘格标定，或用头双目做粗深度。

- 数据是**成功演示**，没有失败标签；这意味着“抓取位姿 → 成功”的因果效应不能只靠演示识别，必须加仿真干预或真机 A/B。

### 1.5 头双目深度精度：够做“锚点”，不够做“最后 1 厘米”

用 `f≈282 px`、`B=58.25 mm`：

```text
Z = fB / d
∂Z/∂d = -Z² / (fB)
```

| 工作距离 Z | 视差 d | 深度误差 / 1 px 视差 | 0.25 px 子像素误差 |
|---:|---:|---:|---:|
| 0.5 m | 32.8 px | 15.2 mm | 3.8 mm |
| 0.7 m | 23.5 px | 29.8 mm | 7.5 mm |
| 1.0 m | 16.4 px | 60.9 mm | 15.2 mm |

**结论**：头双目可以估“物体/受器在哪里、朝哪”，但不足以直接给毫米级抓取位姿。抓取位姿的最后 1–2 cm 必须靠腕部近景 + 相对目标 + 视觉伺服，而不是靠头双目绝对深度。这和第 12 轮 CHUNK-SERVO 的分工一致。

### 1.6 头部方案：都在“动作 chunk”层面竞争，没人显式管“任务兼容抓取位姿”

| 模型家族 | 公开路线 | 与本轮相关的缺口 |
|---|---|---|
| **MolmoAct2** | Ai2 的 action reasoning model；Molmo 2-ER + action expert + adaptive depth reasoning；强调 3D 空间推理、无 per-task 微调 | 输出仍是动作 chunk；没有显式的“任务兼容抓取模式”选择；深度推理不等于抓取位姿闭环 |
| **WALL-OSS-0.5** | X Square 4B VLA（3B VLM + action expert）；公开材料称 15 个真机任务 60.5% average task progress | progress ≠ success；最后一步失败就 0 分；早期抓取错误会被长程任务放大 |
| **DreamZero** | 14B Wan2.1 video-diffusion world-action model；先预测未来视频再出动作 | 世界模型解决“想象未来”，不直接解决“现在抓哪、怎么抓”；14B 推理重，chunk 更长 |
| **π0.5** | Physical Intelligence 开放世界泛化 VLA | 语义/新场景强；接触密集任务的抓取精度不是它的优化目标 |
| **GigaBrain-0** | 世界模型生成数据 + VLA | 生成数据的物理保真度影响抓取位姿精度；最后 3 厘米仍靠执行层 |
| **GR00T N1.5** | NVIDIA 通用人形 VLA | 生态/embodiment 强；任务特定抓取几何仍需额外层 |

共同点：

- 都是 **action chunk 开环执行**，chunk 内不看新图。
- 都从演示里学“动作轨迹”，但**没有把抓取位姿显式参数化**；多模态抓取在回归损失里容易平均成一个“中间抓法”。
- 都没有**失败归因**：抓空、抓滑、抓错部位、放错位置，在模型看来都是“下一帧动作不对”。
- 单模型规则堵死了“再加一个学习抓取模型”的捷径，但没堵死“演示索引 + 几何 + 控制 + 因果表”的确定性层。

### 1.7 近期工作：可借鉴，但不能直接搬

- **DemoGrasp**（arXiv 2509.22149，ICLR 2026）：单条演示 + RL 编辑 wrist pose/hand pose，仿真大规模训练，再蒸馏成视觉策略。可借鉴“把抓取分解成 where/how”；但它需要一个 RL 策略，且是仿真到真机，不适合单模型规则。
- **RAGrasp**（arXiv 2610.04438，2026-10-03）：RGB-D 平面抓取模板检索。可借鉴“检索增强抓取”；但它依赖 depth，挑战赛 API 没有 depth。
- **OpenSPM**（arXiv 2606.29936，2026-07-05）：关键空间位姿记忆 + 闭环 flow matching。可借鉴“相对位姿记忆”；但它需要额外生成模型，单模型风险高。
- **GTP-FA**（arXiv 2606.03385，2026-10-27）：Grasp-Then-Plan + 学习式 failure attribution，公开称把 π0.5 从 11.2% 提到 76.8%（5 个真机任务，各 50 trials）。这是最强的“抓取层值得做”的信号；但它学了一个 failure discriminator，可能被算作第二个模型。本轮用**离线因果风险表 + 确定性归因规则**替代在线学习判别器。
- **IDR**（arXiv 2607.25516，2026-07-28）与 **ActGaze**（arXiv 2609.28955，2026-09-24）：用反事实视觉干预诊断/改进 VLA。可借鉴“干预”的思想；但它们改的是 VLA 的视觉注意力/测试时动作，不是抓取模式选择。
- **ComPose**（arXiv 2605.23523）与 **MG-Grasp**（arXiv 2603.16270）：RGB 下的 6D 物体位姿/抓取重建。可借鉴几何；但它们都是学习模型，不能在线加载。
- **Particle filter for grasp/pose**（如 arXiv 2608.17601 的触觉粒子滤波）：可借鉴“多假设 + 对称性保持”；但挑战赛没有触觉，且我们需要的是“任务兼容抓取位姿”，不是纯物体位姿。

**本轮的差异化**：不是再做一个 6D 抓取网络，而是把**33k 成功演示里的任务兼容抓取**变成静态索引；在线只做检索、粒子共识和因果门控；所有学习都留在官方 VLA 里。

## 2. 诊断：为什么“抓取位姿”是第一瓶颈

把一次 episode 拆成五段：

```text
A 接近（pre-grasp） → B 抓取（grasp pose + close timing） → C 搬运 → D 放置/插入 → E 收尾
```

第 12 轮主要修 D/E 的最后 3 厘米；但 A/B 的错误会直接让 C/D/E 没有意义。具体有五个机制：

1. **任务兼容性 ≠ 抓取稳定性。** 一个杯子可以从侧面抓、从杯口抓、从把手抓；只有“把手朝向可挂”的抓法能完成任务。通用 6D 抓取质量函数（force closure、抗滑）不知道下游要挂杯。
2. **VLA 的动作回归会平均多模态。** 演示里同一个物体有多个成功抓法；MSE/flow 损失在动作空间里可能学出一个“介于两种抓法之间”的轨迹，结果两种都不像。
3. **位置泛化把绝对位姿记忆打死。** 数据审计显示 HangCup 抓取点跨 17–22 cm；任何固定 base 系抓取点都会失效。
4. **手别/双手时序是离散决策，不是连续动作。** PlugInEthernet 211/211 右手先、左手后；VLA 如果先出左手，后面全错。连续动作模型对离散手别选择不敏感。
5. **没有失败标签，VLA 不知道该改哪。** 抓空、抓滑、抓错部位、放错位置，观测上都只是“下一帧图像不一样”；没有归因，就没有有效重试。

**所以本轮的切入点不是“更大模型”，而是“显式抓取变量 + 演示先验 + 因果门控 + 执行闭环”。**

## 3. 方法：GRASP-SWARM

### 3.1 总架构

```text
                         ┌──────────────────────────────────────────┐
                         │  Evaluator (N ports 8765..8765+N-1)      │
                         └──────────────────┬───────────────────────┘
                                            │ websocket: obs / action chunk
                                            ▼
                         ┌──────────────────────────────────────────┐
                         │  Per-port PolicyService (CPU)            │
                         │  ├─ VLA plan cache (30-step, async)      │
                         │  ├─ anchor pose estimator (stereo/wrist) │
                         │  ├─ GPF retrieval + particle swarm       │
                         │  ├─ causal risk gate + failure diagnosis │
                         │  ├─ bimanual phase graph                 │
                         │  └─ CHUNK-SERVO (5-step execute)         │
                         └──────────────────┬───────────────────────┘
                                            │ async, batched
                                            ▼
                         ┌──────────────────────────────────────────┐
                         │  Shared VLA server (GPU, one model)      │
                         │  UnifoLM-WLA-1.0 / VLA-0, 30-step        │
                         └──────────────────────────────────────────┘
```

- **唯一学习模型**：官方 VLA（WLA 微调 action head）。
- **确定性抓取层**：GPF 检索 + 粒子滤波 + 风险表 + 视觉伺服；无在线学习权重。
- **静态资产**：GPF 索引、抓取模式库、风险表；所有端口只读共享，在线状态每端口隔离。
- **数字孪生**：只做离线 PSO 评估、因果干预和标定，不训练策略。

### 3.2 离线：从演示到“抓取位姿场”

对每个任务、每个阶段、每只手：

```text
1. 抓取事件检测
   g_t = gripper_state(t)
   事件起点：g 从 >4.0 首次降到 <1.0；事件终点：g 回升 >4.0 或 episode 结束
   记录：手别、闭合时刻、闭合宽度、闭合前后 10 帧 EE 位姿

2. 锚点选择
   anchor = 任务相关的物体/受器（杯、插头、网口、试管架、拉链头、锁孔、盒子）
   用头双目 + 局部平面/边缘/圆柱拟合，或腕部近景 + 演示模板，估计 T_base_anchor(t)

3. 相对抓取位姿
   T_anchor_ee*(k) = T_base_anchor(k)^-1 · T_base_ee(k)
   同时存：接近方向 v_approach、闭合宽度 w*、闭合时机 τ*、腕部目标图 I_wrist(k)

4. 索引
   key = (task_id, phase_id, hand, anchor_type)
   value = {T_anchor_ee*, v_approach, w*, τ*, I_wrist, descriptor, quality}
```

关键点：

- **相对位姿**而不是绝对位姿：位置泛化/人为干扰下，只要 anchor 重新估计，抓取目标跟着走。
- **任务/阶段/手别条件化**：同一个杯子，HangCup 的抓法和 StackCups 的抓法可以不同；同一个插头，PlugInEthernet 和 DisconnectEthernet 的抓法也可以不同。
- **接近方向**单独存：很多抓取失败不是位置错，而是从错误方向进（从上方压、从侧面撞）。
- **闭合宽度/时机**单独存：夹爪没有力/触觉，闭合宽度是唯一接触代理。

### 3.3 离线：PSO 选“少而鲁棒”的抓取模式

每个任务/阶段可能有很多成功抓取。不要在线检索 33k 条，而是离线压成 3–5 个模式：

```text
候选：对每个 key 的 T_anchor_ee* 做 SE(3) 聚类（或按 anchor 类型/手别分组）
目标：选一组模式中心 M = {m_1..m_K} 和容差半径 r = {r_1..r_K}
适应度：
  F(M,r) = E_{x ~ D_scenarios} [ max_{m∈M, ||δ||≤r_m} Y_sim(m, δ, x) ]
           - λ1·K - λ2·collision_rate - λ3·cycle_time
场景分布 D_scenarios：位置偏移、干扰物、背景、未见物品、人为移动
```

- PSO 的粒子 = 一个候选模式库（中心 + 半径 + 手别/阶段标签）。
- 每个粒子在数字孪生里跑固定数量的抓取 rollouts；用成功率、碰撞、时间做适应度。
- 输出：每任务 3–5 个模式，每个模式带一个“鲁棒半径”和一个“风险等级”。
- 这不是在线学习；PSO 只在离线跑一次，产物是一个静态 JSON/NPZ。

**为什么是 PSO 而不是枚举**：模式中心/半径是连续变量，场景分布是五个泛化轴的组合；枚举成本高，PSO 的种群并行和快速收敛适合这种中小规模连续优化。它也不是“群体智能”的装饰：离线种群搜索 + 在线粒子共识，两个层次都用“多假设 + 交互”的思路。

### 3.4 在线：128 个抓取粒子的共识

每只手维护一个粒子集：

```text
粒子 i: g_i = (T_anchor_ee,i, w_i, v_approach,i, mode_id_i, hand_i)
权重 w_i ∝ prior_i · visual_i · geometry_i · kinematic_i · causal_i · bimanual_i
```

- **先验**：从 GPF 模式库采样；80% 从 top-3 模式，20% 从全库（保留探索）。
- **视觉**：腕部当前 ROI 与演示目标图 I_wrist 的 ORB/轮廓/颜色直方图匹配；头双目局部几何与演示点云模板的 ICP 残差。
- **几何**：抓取方向与局部表面法向的夹角、夹爪开口与物体宽度估计的匹配、是否穿过桌面/障碍。
- **运动学**：IK 可达、关节限位、碰撞距离。
- **因果**：风险表给该模式/偏移/宽度的成功先验（离线校准）。
- **双手**：相对位姿先验 `T_left_right*` 与演示一致；阶段图约束“谁先谁后”。

共识不是简单取最大权重粒子，而是：

```text
1. 按 mode_id + SE(3) 距离聚类；
2. 对每个簇求加权 Frechet/SE(3) 均值与协方差；
3. 选总权重最大的簇；若与第二簇的权重差 < margin，保留两簇；
4. 若协方差 > 阈值，退到“安全 pre-grasp”，移动到一个更好的观察位再更新；
5. 输出 g* = 选中簇的均值；协方差作为不确定性，传给 CHUNK-SERVO 的增益调度。
```

这样做的三个好处：

- **不押单点**：多模态抓取不会被平均掉；保留第二模式，失败后可切换。
- **可解释**：每个粒子的权重来源可记录，失败时能说清是视觉、几何、运动学还是因果风险导致的。
- **CPU 轻量**：128 粒子 × 6D + 简单特征匹配，单端口 <30 ms；不抢 VLA 的 GPU。

### 3.5 因果：从“演示先验”到“干预风险表”

演示全是成功样本，不能直接估计“抓取位姿 → 成功”的因果效应。我们分三步：

1. **定义变量**：
   - 处理 `A`：相对抓取偏移 `(Δx, Δy, Δz, Δroll, Δpitch, Δyaw)`、闭合宽度 `w`、接近方向 `v`、手别 `h`。
   - 结果 `Y`：任务成功（0/1）；辅助结果：抓取滑移、重抓次数、阶段进度。
   - 上下文 `X`：任务、阶段、物体类别、anchor 位姿、背景、干扰物、是否人为干扰。
2. **仿真干预**：在数字孪生里对每个模式采样 `do(A=a)`，跑抓取 + 下游放置；得到 `P(Y=1 | do(A=a), X=x)` 的经验表。
3. **真机校准**：在单任务通道做小规模 A/B（例如每个任务 10–20 次），用层次贝叶斯/温度缩放把仿真风险表校准到真机；只信**排序**，不信绝对概率。

因果估计式：

```text
τ(a,x) = E[Y | do(A=a), X=x] - E[Y | do(A=a0), X=x]
```

在线只用 `R(a,x) = P(Y=1 | do(A=a), X=x)` 做门控和重试排序；不做“因果发现”，也不声称从演示里估出了因果。

**失败归因规则**（确定性决策树，不用第二个模型）：

| 观测症状 | 最可能原因 | 动作 |
|---|---|---|
| 预抓取视觉残差高 / anchor 协方差大 | 感知/锚点位姿 | 重估 anchor，换视角，腕部近景 |
| 夹爪闭合后宽度接近 0 | 抓空/抓偏 | 沿接近方向平移 3–5 mm，重采粒子 |
| 夹爪闭合后宽度异常大 | 抓得太靠外/物体太大 | 换模式或调整闭合时机 |
| 物体随夹爪动但相对滑动大 | 抓取宽度/高度不对 | 加大闭合、换抓取高度、降速 |
| 物体不动、夹爪闭合 | 抓滑/抓错部位 | 切换第二模式，重抓 |
| 外部物体突然移动 | 人为干扰 | 停、重定位、重规划 |
| 双手相对位姿超界 | 双手协调 | 调整相对位姿/顺序，避免碰撞 |

这张表把第 11 轮 GEO-RESIDUAL 的 `d_t, n_t, r_static, r_grasp, edit_score` 接到抓取层：`r_grasp` 突变 = 滑移；`edit_score` 高 = 人为干扰；`d_t` 小 = 接触段。

### 3.6 双手：相对位姿 + 阶段图

- 从演示里抽“右手先抓、左手后抓”的时序；每个阶段的 `T_left_right*` 存成相对位姿先验。
- 在线粒子滤波给每只手单独维护粒子，但加一个**相对位姿约束**：`||log(T_left_right^-1 T_left_right*)|| ≤ ε`。
- 阶段图：`approach_R → grasp_R → approach_L → grasp_L → lift → insert`；如果 VLA 的 phase 与图冲突，优先按图执行，因为图来自成功演示。
- 双手碰撞检查：用简化胶囊/包围盒，检查两腕和夹爪之间的最小距离。

数据审计显示 PlugInEthernet 的左右手相对平移 std 约 3–4 cm、相对旋转 std 约 7–11°；这比绝对位姿的 yaw std（24°）稳定，说明相对约束是有效的。

### 3.7 与 CHUNK-SERVO 的接口

```text
VLA plan (30 steps)  →  前馈轨迹
GPF/particle g*      →  抓取目标（相对 anchor）
CHUNK-SERVO          →  每 5 步闭环修正，接触段法向缩幅
gripper close        →  d_t < d_c 或视觉误差 < ε 连续 K 帧
slip monitor         →  r_grasp 突变 → 重抓/换模式
```

- 抓取层只覆盖“抓取目标 + 闭合时机”，不覆盖 VLA 的语义计划和搬运/放置轨迹。
- 如果 GPF 置信度低，回退到 VLA 的抓取目标；如果 VLA 也没有明确抓取点，回退到开环 chunk。
- 抓取层的输出是相对位姿，CHUNK-SERVO 的 PBVS/IBVS 直接用它做目标；坐标系与第 12 轮一致。

### 3.8 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线索引 | GPF/风险表离线构建；在线只检索/几何/控制 | 最低 | **主推** |
| C2 确定性控制器 | 粒子滤波、PSO、风险表都是确定性/无学习权重 | 低 | **主推** |
| C3 同 checkpoint 特征 | 若需要强描述子，用 VLA 同一 checkpoint 的 encoder | 低–中 | 可选 |
| 禁止 | 在线加载第二个学习抓取模型/残差策略/独立视觉编码器决策 | 高 | 不做 |

提交材料要写清楚：**一个 VLA + 一个无学习权重的抓取控制器；离线用了仿真和演示索引，没有第二个在线策略。**

## 4. 与第 10–12 轮的关系：保留、升级、剪枝

- 官方 WLA 基座、33k 演示、单任务通道、竞赛组合。

**升级**：

- 从“最后 3 厘米”前移到“最初 3 秒”：加 GPF/粒子抓取层；
- 从“单点抓取”升级为“多模式 + 不确定性 + 共识”；
- 从“演示检索”升级为“演示索引 + 离线 PSO + 因果风险表”；
- 从“单手相对目标”升级为“双手相对位姿 + 阶段图”；
- 从“失败检测”升级为“失败归因 + 重试路由”。

**剪枝**：

- 不做第二个在线学习抓取模型（单模型风险）；
- 不做 RGB-D 抓取模板（API 没有 depth）；
- 不做跨端口在线学习/共享 episode 状态（规则要求隔离）；
- 不做完整因果发现/因果世界模型（算力/数据/延迟不划算）；
- 不做 32 个任务各一个抓取策略（规则禁止，且不泛化）；
- 不做力/触觉闭环（API 没有）；
- 不把旧榜单的任务排名当失败分布（已证伪）。

## 7. 竞赛策略：先测“抓取阶段失败占比”，再决定投多少

- 单任务通道先测 5 个代表任务：HangCup（挂）、PlugInEthernet（双手插入）、ZipUp（拉链）、StackBowls（叠）、FoldTowel（变形，防回归）。
- 每个任务 10 次 baseline；人工/半自动标注失败阶段：A 接近、B 抓取、C 搬运、D 放置/插入、E 收尾。
- 计算 `q_t = B 阶段失败 / 总失败`；如果 5 个任务里 B 阶段占比 <20%，本轮抓取层降级，只保留 I5/I6，把工程转回 CHUNK-SERVO 的 D/E 段。
- 如果 B 阶段占比高（尤其 HangCup/PlugInEthernet），按 `q_t × Δ / cost` 排优先级；先做 3–5 个任务，不一次铺 19 个。
- 正式提交前保留回滚开关：GPF 置信度低/延迟高/异常时，自动回退到第 12 轮 CHUNK-SERVO 基线。

## 8. 主要风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 成功演示没有失败标签 | 因果效应不可识别 | 仿真干预 + 真机 A/B；只信排序 |
| 头双目深度噪声大 | anchor 位姿误差 | 腕部近景 + 相对位姿 + 视觉伺服；不靠绝对深度 |
| 腕部无内参 | 2D 对齐不准 | 一次性棋盘格标定；D435 先验；头双目兜底 |
| 透明/反光/变形物体 | 几何/特征失败 | 只对刚体任务启用；回退 VLA |
| 未见物品 | 演示索引 mismatch | 任务/阶段/anchor 条件化；几何/视觉重打分；VLA 语义 |
| 粒子滤波延迟 | 影响远程 API | 128 粒子、CPU、向量化；p99 门 |
| 单模型解释 | 被判第二个模型 | C1/C2；提交材料写明；不做在线学习 |
| 双手碰撞 | 安全/失败 | 相对位姿约束 + 胶囊碰撞 + 限速 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |

## 9. 一句话押注

**把 33k 成功演示变成一张按任务/阶段/手别条件化的抓取位姿场，用离线 PSO 选鲁棒模式、在线粒子群共识估计 6D 抓取位姿、用因果风险表做门控，再把选中的抓取目标交给 CHUNK-SERVO 的 5 步闭环——在单模型规则下，把失败从“最后 3 厘米”前移到“最初 3 秒”去解决。**

# 第 13 轮产物 · GRASP-SWARM 技术报告

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「GRASP-SWARM」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是在它们前面加一层“任务兼容抓取位姿”的显式控制变量。

## 0. 结论与边界

### 0.1 一句话结论

**从 33k 条成功演示里挖出按任务/阶段/手别条件化的相对抓取位姿场（GPF），离线用 PSO 压成 3–5 个鲁棒抓取模式，在线用 128 个抓取粒子做共识估计，用干预校准的因果风险表做模式门控与失败归因，再把选中的抓取目标交给 CHUNK-SERVO 的 5 步闭环执行。** 这样不新增在线学习模型，却把 VLA 隐式的“抓取动作”变成显式的、可检索、可干预、可恢复的控制变量。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、排行榜 JSON 直接核实 | 规则、API、33,276 eps、WLA chunk=30、旧榜单 29.7% |
| B | 我们在公开数据/网页上做的分析，可复现 | HangCup/PlugInEthernet 抓取事件统计、头双目深度误差 |
| C | 设计假设，需 G0–G8 验证 | 粒子共识 ≤5 mm、因果表排序 Spearman ≥0.6、真机 +10pp |

### 0.3 本轮不做什么

- 不从零训 VLA/World Model；官方 WLA 已开源 6B 基座。
- 不做第二个在线学习抓取模型；GPF/PSO/风险表都是离线资产 + 确定性在线控制器。
- 不做 RGB-D 抓取模板；API 没有 depth，头双目只做粗锚点。
- 不做跨端口在线学习；规则要求每端口 `reset()`/历史隔离。
- 不做完整因果发现/因果世界模型；只做“仿真干预 + 真机校准”的风险表。
- 不做力/触觉闭环；API 没有。
- 不把旧榜单的任务排名当失败分布；只当难度信号。

### 0.4 与第 12 轮的关系

| 第 12 轮 | 第 13 轮 |
|---|---|
| 30 步 VLA 规划 + 5 步视觉伺服 | 保留；抓取目标也走 5 步伺服 |
| 演示检索“受器→夹爪”相对位姿 | 扩展为任务/阶段/手别条件化的 GPF |
| 数字孪生标定 RTT/增益/外参 | 增加 `do(抓取位姿)` 干预，生成风险表 |
| 失败检测（编辑/接触） | 增加抓取失败归因与重试路由 |
| 竞赛组合按 `q_t×Δ/cost` | 先用单任务通道测“抓取阶段失败占比” |

- 抓取层必须 CPU 轻量，不能抢 VLA 的 GPU；p99 延迟要进 G7。

### 1.5 提交 API（A，2026-10-31 复核）

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`，480×640 RGB |
| 本体 | 双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base）、夹爪 `[1]`、`lower_body [15]`、语言 `str` |
| 动作空间 | `control_space` 仅 `"joint"` 或 `"ee"`，互斥 |
| 共享动作 | `action.left_gripper [1]`、`action.right_gripper [1]`、`action.pivot [7]` |
| EE 动作 | `action.left_ee_pose_gripper_base [6]`、`action.right_ee_pose_gripper_base [6]`（绝对目标位姿，xyz+rpy，base） |
| chunk | `action_chunk_size` ≥1，固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action` |
| token | `metadata.token` 握手校验；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile** |
| 监控 | 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分 |

**关键推论**：`action_chunk_size=30`、30Hz 时，一次 `get_action` 后有 **1 秒开环执行**；chunk 内没有新观测，也没有打断机制。抓取层如果要闭环，必须把执行 chunk 降到 3–8 步，或把 VLA 规划与抓取/伺服执行拆成双频。第 12 轮默认 `H_c=5`（167 ms）。

### 1.7 头双目深度精度（B，派生）

用 `f≈282 px`、`B=58.2526 mm`：

```text
Z = fB / d
∂Z/∂d = -Z² / (fB)
```

| Z | d | 误差 / 1 px 视差 | 0.25 px 子像素 |
|---:|---:|---:|---:|
| 0.5 m | 32.8 px | 15.2 mm | 3.8 mm |
| 0.7 m | 23.5 px | 29.8 mm | 7.5 mm |
| 1.0 m | 16.4 px | 60.9 mm | 15.2 mm |

**结论**：头双目可以估“锚点在哪里、朝哪”，但不足以给毫米级抓取位姿；最后 1–2 cm 必须靠腕部近景 + 相对目标 + 视觉伺服。这直接决定了 GPF 必须用**相对位姿**，而不是绝对深度。

### 1.8 数据审计：HangCup 与 PlugInEthernet（B，2026-10-31）

#### 方法

- 数据：HF 数据集 `G1_Dex1_HangCup`、`G1_Dex1_PlugInEthernet` 的首个 parquet 分片（`data/chunk-000/file-000.parquet`，各约 100 MB）。
- 列：`observation.state.left_gripper`、`right_gripper`、`left_ee_pose_gripper_base`、`right_ee_pose_gripper_base`、`episode_index`、`timestamp`。
- 抓取事件：夹爪从 `>4.0` 首次降到 `<1.0`；若之后回升到 `>4.0`，可检测第二次抓取。
- 位姿：事件帧的 EE 位姿（base 系，xyz+rpy）。
- 局限：只看了首个分片，不是全量；没有物体位姿标签；全是成功演示。

#### 结果

| 任务 | 分片 episodes | 事件/ episode | 手别 | 首次闭合中位 | 闭合开口中位 | 抓取 xyz std (cm) | 姿态 std (rad) |
|---|---:|---|---|---:|---:|---|---|
| HangCup | 719 | 1 次 716；2 次 3；0 次 0 | 右手 716 / 左手 3 | 2.20 s | 0.83 / 5.5 | **5.1, 7.1, 2.1** | 0.175, 0.126, **0.364** |
| PlugInEthernet | 211 | 2 次 211；0/1 次 0 | 右手先、左手后 211 | 右手 2.77 s；左手 5.80 s | 0.88–0.89 / 5.5 | 左手 2.4, 3.1, 0.5；右手 3.7, 4.2, 0.6 | 右手 yaw **0.412** |

#### 解释

1. **绝对抓取位姿方差大**：HangCup 的 x 5%–95% 分位为 24.1–41.6 cm（跨 17.5 cm），y 为 -37.6 到 -15.8 cm（跨 21.8 cm），yaw std 20.8°。固定 base 系抓取点会在位置泛化轴上失效。
2. **手别是离散决策**：HangCup 716/719 右手；PlugInEthernet 211/211 右手先、左手后。通才模型必须从任务/阶段/演示里推断手别，不能只回归连续动作。
3. **双手相对位姿比绝对位姿稳定**：PlugInEthernet 在左手抓取时刻，右→左相对平移 std 约 3.7/3.2/3.1 cm，相对旋转 std 约 7.4°/10.3°/10.9°；而右手绝对 yaw std 23.6°。相对约束更稳。
4. **抓取发生得早**：HangCup 2.2 s / 5.8 s；PlugInEthernet 2.8 s / 19.1 s。抓取错误会被长程任务放大。
5. **闭合宽度是可用接触代理**：闭合后开口约 0.83–0.89（量程 5.5），约 15–16% 全开；可用来检测抓空/抓偏/抓太大。

#### 局限

- 只覆盖 2 个任务的首个分片；不能外推到 32 任务。
- 没有物体位姿，无法直接算“物体相对抓取误差”；需要头双目/腕部重建或仿真真值。
- 全是成功演示，无法估计失败率或因果效应；必须加仿真干预/真机 A/B。
- 抓取事件检测阈值 4.0/1.0 是启发式；需要 G0 用人工标注校准。

- 都是 action chunk 开环执行，chunk 内不看新图。
- 都从演示学“动作轨迹”，但没有把抓取位姿显式参数化；多模态抓取在回归损失里容易平均。
- 都没有失败归因：抓空、抓滑、抓错部位、放错位置，在模型看来都是“下一帧动作不对”。
- 单模型规则堵死“再加一个学习抓取模型”，但没堵死“演示索引 + 几何 + 控制 + 因果表”的确定性层。

## 2. 问题形式化

### 2.1 失败链与符号

一次 episode 的五段：

```text
A 接近（pre-grasp） → B 抓取（grasp pose + close timing） → C 搬运 → D 放置/插入 → E 收尾
```

记：

- `T_base_ee(t)`：夹爪在 base 系的位姿；
- `T_base_anchor(t)`：任务锚点（物体/受器）在 base 系的位姿；
- `T_anchor_ee(t) = T_base_anchor(t)^-1 T_base_ee(t)`：相对抓取位姿；
- `h ∈ {L,R}`：手别；
- `w`：夹爪闭合后的开口；
- `τ`：闭合时刻/阶段；
- `Y ∈ {0,1}`：任务成功。

抓取层要输出：

```text
g* = (T_anchor_ee*, h*, w*, τ*, v_approach*)
```

其中 `v_approach*` 是接近方向。注意：这不是“抓稳”意义上的抓取，而是**任务兼容**意义上的抓取；`Y` 是完整任务成功，不是抓取成功。

### 2.2 抓取位姿场（GPF）

对任务 `t`、阶段 `p`、手别 `h`、锚点类型 `a`：

```text
D_{t,p,h,a} = { (T_anchor_ee*(k), v*(k), w*(k), τ*(k), I_wrist(k)) }
```

用 SE(3) 上的混合核表示：

```math
p(G \mid t,p,h,a)
= \sum_{k=1}^{K} \pi_k \, \mathcal{N}_{SE(3)}(G; \mu_k, \Sigma_k)
```

其中 `μ_k` 是模式中心，`Σ_k` 是切空间协方差，`π_k` 是权重。`K` 不需要等于演示数；离线 PSO 会把它压到 3–5。

检索打分：

```math
S(g) = w_v S_{vis}(g) + w_g S_{geo}(g) + w_k S_{kin}(g)
     + w_c S_{causal}(g) + w_b S_{bimanual}(g)
```

- `S_vis`：腕部 ROI 与演示目标图的 ORB/轮廓/颜色直方图相似度；
- `S_geo`：头双目局部点云与演示模板的 ICP 残差、抓取方向与表面法向夹角；
- `S_kin`：IK 可达、关节限位、碰撞距离；
- `S_causal`：风险表给出的成功先验；
- `S_bimanual`：双手相对位姿先验一致性。

### 2.3 因果估计

定义处理 `A`、结果 `Y`、上下文 `X`：

```text
A = (Δx, Δy, Δz, Δroll, Δpitch, Δyaw, w, v, h)
Y = 任务成功（0/1）；辅助：滑移、重抓、阶段进度
X = (task, phase, object_class, anchor_pose, background, distractor, human)
```

目标：

```math
\tau(a,x) = \mathbb{E}[Y \mid do(A=a), X=x]
          - \mathbb{E}[Y \mid do(A=a_0), X=x]
```

识别假设：

1. **一致性**：干预值就是实际执行的抓取参数；
2. **正性**：仿真里每个模式附近都采样到成功/失败；
3. **无未观测混杂**：仿真全状态；真机校准阶段尽量配对初始条件；
4. **可迁移性**：仿真效应排序可迁移到真机（只信排序，不信绝对值）。

数据来源：

- 演示：提供成功抓取的支持集，不提供反事实；
- 数字孪生：提供 `do(A)` 下的成功/失败；
- 单任务通道：提供少量真机配对 A/B，用于校准。

风险表模型（离线拟合，在线只查表）：

```math
R(a,x) = \sigma\!\left(\beta_0 + \beta^\top \phi(a,x)\right)
```

`φ` 用低维特征：偏移范数、角度偏差、宽度匹配、接近方向夹角、手别、任务/阶段 one-hot、锚点协方差、背景/干扰标志。**不用神经网络在线推理。**

### 2.4 粒子滤波

每只手 `h` 维护 `N=128` 个粒子：

```text
g_i = (T_anchor_ee,i, w_i, v_i, mode_id_i, hand_i)
```

权重：

```math
w_i^{(t)} \propto w_i^{(t-1)} \,
\frac{p(z_t \mid g_i) \, p(g_i \mid t,p,h,a)}{q(g_i)}
```

其中：

- `p(g_i | ...)` 是 GPF 先验（模式混合）；
- `p(z_t | g_i)` 是视觉/几何/运动学/因果/双手似然的乘积；
- `q(g_i)` 是提议分布（模式采样 + VLA 目标 + 几何提议）。

共识：

```math
g^* = \arg\max_{C \in \text{clusters}}
      \sum_{i \in C} w_i
```

并要求：

```text
margin = (W_top1 - W_top2) / W_top1 ≥ θ_m
```

如果 `margin < θ_m`，保留 top-2 模式；如果协方差 `tr(Σ_C) > θ_Σ`，退到安全 pre-grasp 再观察。

### 2.5 双手相对位姿

定义：

```math
T_{L \leftarrow R} = T_{base,L}^{-1} T_{base,R}
```

演示里存 `T_{L \leftarrow R}^*`；在线约束：

```math
\left\| \log\!\left(T_{L \leftarrow R}^{-1} T_{L \leftarrow R}^*\right) \right\| \le \epsilon
```

阶段图：

```text
approach_R → grasp_R → approach_L → grasp_L → lift → insert/place
```

如果 VLA 的 phase 与图冲突，优先按图执行；图来自成功演示，且任务级语言不变。

### 2.6 任务兼容抓取分数

普通抓取质量 `Q_stable` 只衡量抗滑/力闭合；我们需要：

```math
Q_{task}(g) = Q_{stable}(g) \cdot
P(Y=1 \mid do(g), task, phase)
```

- `Q_stable` 用几何近似：抓取宽度与物体宽度匹配、接触法向、夹爪不穿模；
- `P(Y=1 | do(g), ...)` 来自风险表；
- 两者相乘，避免“抓得稳但没法挂/插”的抓法。

### 3.2 PSO 模式选择

粒子 = 一个候选模式库：

```text
particle = {
  centers: [m_1..m_K],       # SE(3)
  radii:   [r_1..r_K],       # 平移/旋转容差
  hand:    [h_1..h_K],
  phase:   [p_1..p_K]
}
```

适应度：

```math
F(M,r) = \mathbb{E}_{x \sim D_{scenarios}}
\left[
\max_{m \in M,\ \| \delta \| \le r_m}
Y_{sim}(m,\delta,x)
\right]
- \lambda_1 K - \lambda_2 \, \text{collision}
- \lambda_3 \, \text{cycle\_time}
```

场景分布 `D_scenarios`：

- 位置偏移：±5–15 cm，±10–30°；
- 干扰物：桌面随机放 1–3 个无关物体；
- 背景：桌布颜色/纹理替换；
- 未见物品：同类不同颜色/形状/材质；
- 人为移动：抓取前/中移动物体 2–10 cm。

约束：

- 每个模式至少覆盖 10% 的演示抓取；
- 模式之间 SE(3) 距离 ≥ 最小间隔；
- 每个模式的仿真成功率 ≥ 基线；
- 优先保留“手别/阶段”不同的模式，而不是同一抓法的抖动。

### 3.3 在线粒子滤波

```python
class GraspParticleFilter:
    def __init__(self, gpf, risk, n=128):
        self.gpf = gpf
        self.risk = risk
        self.n = n
        self.particles = None

    def reset(self, task, phase):
        self.particles = self.gpf.sample(task, phase, self.n)
        self.weights = np.ones(self.n) / self.n

    def update(self, obs, anchor_pose, vla_target=None):
        # 1. 预测：随 EE 运动传播，加小扩散
        self._propagate(obs.ee_pose, sigma=0.002, sigma_rot=0.01)

        # 2. 注入提议：VLA 目标 / 几何提议
        if vla_target is not None:
            self._inject(vla_target, fraction=0.2)
        self._inject_geometric(obs, fraction=0.1)

        # 3. 似然：视觉 + 几何 + 运动学 + 因果 + 双手
        logw = (
            self._visual_loglik(obs, anchor_pose)
            + self._geometry_loglik(obs, anchor_pose)
            + self._kinematic_loglik(obs, anchor_pose)
            + self._causal_loglik(anchor_pose, obs.task, obs.phase)
            + self._bimanual_loglik(obs)
        )
        self.weights *= np.exp(logw - logw.max())
        self.weights /= self.weights.sum()

        # 4. 重采样（系统重采样，保留模式）
        if 1.0 / np.sum(self.weights ** 2) < self.n / 2:
            self._systematic_resample()

    def consensus(self):
        clusters = self._cluster_by_mode_and_se3()
        clusters.sort(key=lambda c: c.weight, reverse=True)
        top1, top2 = clusters[0], clusters[1] if len(clusters) > 1 else None
        margin = 1.0 if top2 is None else (top1.weight - top2.weight) / top1.weight
        if margin < 0.15:
            # 保留 top-2，先做安全 pre-grasp
            return None, clusters[:2]
        return top1.mean, clusters[:1]
```

### 3.4 因果风险表

离线：

```text
for task, mode in modes:
    for delta in sample_grid(mode.radius):
        for scenario in D_scenarios:
            y = digital_twin.rollout(task, mode, delta, scenario)
            table.add(task, mode, delta, scenario, y)
fit logistic / monotone GAM on features phi(a,x)
calibrate with real A/B (temperature scaling / hierarchical prior)
```

在线：

```text
risk = table.lookup(task, phase, mode_id, delta_bin, hand, anchor_cov, background_flag)
if risk > θ_risk: 降权该粒子
if risk > θ_abort: 不选该模式
```

风险表只用于排序和门控；如果风险表与视觉/几何冲突，优先视觉/几何，风险表只做 tie-break。这样避免“因果表错了导致全错”。

### 3.5 失败归因

| 症状 | 代理信号 | 归因 | 动作 |
|---|---|---|---|
| 预抓取视觉残差高 | `S_vis` 低、anchor 协方差大 | 感知/锚点 | 重估 anchor，换视角，腕部近景 |
| 夹爪闭合后宽度接近 0 | `w < 0.1` | 抓空/抓偏 | 沿接近方向平移 3–5 mm，重采粒子 |
| 夹爪闭合后宽度异常大 | `w > w_max` | 抓得太靠外/物体太大 | 换模式或调整闭合时机 |
| 物体随夹爪动但相对滑动大 | `r_grasp` 突变 | 宽度/高度不对 | 加大闭合、换抓取高度、降速 |
| 物体不动、夹爪闭合 | `r_static` 小、`r_grasp` 大 | 抓滑/抓错部位 | 切换第二模式，重抓 |
| 外部物体突然移动 | `edit_score > θ_e` | 人为干扰 | 停、重定位、重规划 |
| 双手相对位姿超界 | `||log(T_rel^-1 T_rel*)|| > ε` | 双手协调 | 调整相对位姿/顺序，避免碰撞 |
| 动作执行偏差大 | `||a_cmd - a_exec||` 大 | 执行/延迟 | 降增益、加 chunk、重规划 |

重试预算：

- 每次抓取最多 2 次重试；
- 第一次：沿接近方向/法向小偏移；
- 第二次：切换 top-2 模式；
- 两次失败：回退 VLA 开环，避免无限重试。

### 3.6 双手阶段图

```text
states:
  APPROACH_R → GRASP_R → LIFT_R → APPROACH_L → GRASP_L → COORDINATE → PLACE

constraints:
  - GRASP_L 前必须 GRASP_R 成功（PlugInEthernet 类）
  - 双手相对位姿在 ε 内
  - 两腕/夹爪最小距离 ≥ d_safe
  - 若 VLA phase 与图冲突，按图执行
```

实现：

- 每只手一个粒子滤波器；
- 共享一个阶段状态机；
- 相对位姿约束作为一个似然项；
- 碰撞检查用胶囊/包围盒，CPU 足够。

### 3.7 与 CHUNK-SERVO 的接口

```text
VLA plan (30 steps)  →  前馈轨迹
GPF/particle g*      →  抓取目标（相对 anchor）
CHUNK-SERVO          →  每 5 步闭环修正，接触段法向缩幅
gripper close        →  d_t < d_c 或视觉误差 < ε 连续 K 帧
slip monitor         →  r_grasp 突变 → 重抓/换模式
```

动作空间用 `ee`，与 WLA 的相对 EE 动作一致。每个执行块：

```text
a_ff = VLA plan[t : t+H_c]          # H_c = 5
e = servo_error(obs_t, g*)           # 6D
Δ = clip(K_p e + K_d ė, ±δ_p, ±δ_r)
a_cmd = a_ff ∘ exp(Δ)
```

- 抓取层只覆盖“抓取目标 + 闭合时机”，不覆盖 VLA 的语义计划和搬运/放置轨迹。
- 如果 GPF 置信度低，回退到 VLA 的抓取目标；如果 VLA 也没有明确抓取点，回退到开环 chunk。
- 抓取层的输出是相对位姿，CHUNK-SERVO 的 PBVS/IBVS 直接用它做目标。

### 3.10 `get_action` 伪代码

```python
class GraspSwarmPolicy:
    def __init__(self):
        self.vla = VLAClient()
        self.gpf = GPFIndex.load("grasp/gpf_index.npz")
        self.modes = load_json("grasp/modes.json")
        self.risk = load_json("grasp/risk_table.json")
        self.servo = ChunkServo()
        self.pf = { "L": GraspParticleFilter(self.gpf, self.risk),
                    "R": GraspParticleFilter(self.gpf, self.risk) }
        self.phase = PhaseGraph()

    def reset(self):
        self.vla.reset()
        self.servo.reset()
        self.pf["L"].reset(self.task, self.phase.current)
        self.pf["R"].reset(self.task, self.phase.current)
        self.phase.reset()

    def get_action(self, obs):
        # 1. 异步 VLA plan，永不阻塞（冷启动除外）
        self.vla.maybe_request(obs)

        # 2. 锚点位姿
        anchor = estimate_anchor(obs, self.task, self.phase.current)

        # 3. 粒子更新 + 共识
        for h in ("L", "R"):
            self.pf[h].update(obs, anchor, self.vla.grasp_target(h))
        gL, cL = self.pf["L"].consensus()
        gR, cR = self.pf["R"].consensus()

        # 4. 因果门控 / 双手约束
        gL, gR = self.risk.gate(gL, gR, obs, self.phase)
        gL, gR = self.bimanual.constrain(gL, gR, self.phase)

        # 5. CHUNK-SERVO
        if gL is None or gR is None:
            # 低置信度：安全 pre-grasp，等待下一次观测
            return self.servo.safe_hold(obs)
        cmd = self.servo.step(obs, gL, gR, self.vla.plan, H_c=5)

        # 6. 闭合触发 + 滑移监测
        if self.servo.should_close(obs, gL, gR):
            cmd = self.servo.close_gripper(cmd)
        if self.servo.slip_detected(obs):
            self.phase.on_slip()
            self.pf["L"].reweight_failed()
            self.pf["R"].reweight_failed()

        # 7. 失败归因 / 重试
        if self.phase.failed():
            action = diagnose(obs, self.phase)
            self.phase.apply(action)
            self.pf["L"].retry(action)
            self.pf["R"].retry(action)

        return self.adapter.to_api(cmd, obs, token)
```

### 4.3 解释与边界

- 这些数字支持“相对位姿 + 手别 + 时序”的必要性，但**不支持**“抓取层一定涨点”。涨点要在 G4 真机 A/B 里测。
- 只看了首个分片；全量 32 任务需要 G0。
- 成功演示没有失败标签；因果效应需要 G3。
- 抓取事件阈值是启发式；需要人工抽检校准。

| 消融 | GPF/粒子/因果/相对/绝对 | 成功率、误差 |

### 5.6 门 G0–G8

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | 抓取事件/手别/时序能否自动挖？ | 32 任务事件 F1 ≥0.95；手别/顺序与人工抽检一致 ≥95% | 先做 5 个任务，人工标注 |
| G1 | GPF 检索是否可信？ | top-5 含可行且任务兼容抓取 ≥85%；模式覆盖 ≥90%（1 cm/10°） | 退回任务级固定模式 |
| G2 | 粒子共识是否收敛？ | 1–2 cm 内 ≤5 mm/5°；共识 ≥95%；CPU ≤30 ms | 减粒子/退化为模式选择 |
| G3 | 因果风险表是否排序正确？ | 仿真 vs 真机 Spearman ≥0.6；校准误差 ≤0.1 | 只做归因，不做选择 |
| G4 | 真机单任务是否涨点？ | 5 任务 ×10 次 A/B：≥3 任务 +10pp；FoldTowel 不回归 >5pp | 不提交抓取层 |
| G5 | 双手是否协调？ | 相对位姿 ≤1 cm/5°；双手任务 ≥80% | 退回单手/固定顺序 |
| G6 | 人为干扰能否恢复？ | 检测 ≤300 ms；仿真恢复 ≥60% | 只做离线归因 |
| G7 | 32 任务干跑是否稳定？ | N 端口隔离、reset 干净、内存不涨、p99 ≤150 ms | 回退 CHUNK-SERVO 基线 |
| G8 | 消融是否支持因果？ | GPF > VLA-only；粒子 > top-1；因果门控 > 无门控 | 保留有效部分，砍掉无效部分 |

### 5.7 统计

- 总分 `S = (1/32) Σ_t p_t`；320 trials 若 `p≈0.25`，`SE(S)≈2.42pp`；配对设计可降低，但不要用 +1–2pp 做结论。
- 单任务 10 次 A/B 只能看方向；用 5 任务汇总 + bootstrap CI。
- 报告失败阶段分布 `q_t`，不要只报成功率。
- 所有真机 A/B 记录初始条件、背景、物体、干扰类型，避免混淆。

## 6. 竞赛策略

### 6.1 先测“抓取阶段失败占比”

单任务通道 5 个代表任务：

| 任务 | 为什么选 |
|---|---|
| HangCup | 单手、任务兼容抓取（把手/杯口）、位置泛化 |
| PlugInEthernet | 双手、顺序、插入、线缆干扰 |
| ZipUp | 小目标、拉链头、接触密集 |
| StackBowls | 叠放、抓取高度/姿态 |
| FoldTowel | 变形、防回归（抓取层不应伤害它） |

每个任务 10 次 baseline；从视频/日志标注失败阶段 A–E；计算：

```text
q_t = B 阶段失败 / 总失败
```

决策：

- 5 任务平均 `q_t < 20%`：抓取层降级，只保留 I5/I6，把工程转回 D/E 段。
- `q_t ≥ 20%` 且至少 3 个任务 B 阶段失败明显：按 `q_t × Δ / cost` 排序，先做 3–5 个任务。
- 如果 HangCup/PlugInEthernet 的 B 阶段失败占比高，优先这两个（一个单手、一个双手）。

### 6.3 边际收益算术

- 32 任务平均：若 10 个任务各 +10pp → `10/32×10=+3.1pp`；19 个各 +8pp → `+4.8pp`。
- 抓取层只影响 B 阶段；如果 B 阶段失败占总失败 30%，抓取成功率 +15pp，任务成功率约 +4.5pp（近似，非线性）。
- 双手任务（约 10 个）若顺序/相对位姿改善 +10pp → `+3.1pp`。
- 人为干扰轴占 20%；抓取层 + 重定位若 +10pp → `+2pp`。
- 保守合计 **+3–6pp**；乐观 +7–9pp；但必须用配对 A/B 证明，不能承诺。

## 7. 风险与合规

### 7.1 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线索引 | GPF/风险表离线构建；在线只检索/几何/控制 | 最低 | **主推** |
| C2 确定性控制器 | 粒子滤波、PSO、风险表都是确定性/无学习权重 | 低 | **主推** |
| C3 同 checkpoint 特征 | 若需要强描述子，用 VLA 同一 checkpoint 的 encoder | 低–中 | 可选 |
| 禁止 | 在线加载第二个学习抓取模型/残差策略/独立视觉编码器决策 | 高 | 不做 |

提交材料写清楚：

- 一个 VLA（官方 WLA 微调）+ 一个无学习权重的抓取控制器；
- 离线用了数字孪生和演示索引；
- 没有第二个在线策略；
- 粒子滤波/PSO/风险表都不是学习模型。

### 7.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 成功演示没有失败标签 | 因果效应不可识别 | 仿真干预 + 真机 A/B；只信排序 |
| 头双目深度噪声大 | anchor 位姿误差 | 腕部近景 + 相对位姿 + 视觉伺服；不靠绝对深度 |
| 腕部无内参 | 2D 对齐不准 | 一次性棋盘格标定；D435 先验；头双目兜底 |
| 透明/反光/变形物体 | 几何/特征失败 | 只对刚体任务启用；回退 VLA |
| 未见物品 | 演示索引 mismatch | 任务/阶段/anchor 条件化；几何/视觉重打分；VLA 语义 |
| 粒子滤波延迟 | 影响远程 API | 128 粒子、CPU、向量化；p99 门 |
| 单模型解释 | 被判第二个模型 | C1/C2；提交材料写明；不做在线学习 |
| 双手碰撞 | 安全/失败 | 相对位姿约束 + 胶囊碰撞 + 限速 |
| 风险表 sim-to-real gap | 选错模式 | 只用排序；视觉/几何优先；真机校准 |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |
| `pivot` 语义不一致 | 动作被拒/机器人不动 | 先用 `example_env.py`/单任务通道验证；零 pivot 回退 |

### 7.3 安全

- 抓取/重抓限速、限幅、最大重试 2 次。
- 编辑检测/人为干扰触发即停。
- 双手碰撞检查用胶囊/包围盒，保留安全距离。
- 透明/反光/变形物体不硬做几何伺服；回退 VLA。
- 任何异常返回上一组合法 chunk 或安全 hold；绝不返回 NaN/错误形状。

### 7.4 数据泄漏

- GPF 检索评测按 episode/session/物体/背景分组划分。
- 相邻帧不跨 split；同一 episode 的抓取关键帧不能同时出现在检索库和测试集。
- 仿真场景与真机测试物体分开；未见物品轴单独留出。
- 风险表校准用的真机 trials 不能与最终评测任务/初始条件重叠（如果可控制）。

### I5 · GRASP-SERVO：抓取层接 CHUNK-SERVO

| 项 | 内容 |
|---|---|
| **动机** | 选中的抓取位姿必须被执行准；第 12 轮 CHUNK-SERVO 已经解决最后 3 厘米的闭环，本轮把抓取目标接进去，形成“最初 3 秒 + 最后 3 厘米”的完整闭环。 |
| **与现有方案的差异** | vs 纯 VLA chunk：抓取目标不显式；vs 纯几何伺服：没有语义/任务先验；vs 第 12 轮：只做最后 3 厘米，本轮加抓取目标/闭合时机/滑移监测。 |
| **技术可行性** | 高。复用第 12 轮代码；只加目标适配/闭合触发/滑移监测。 |
| **所需资源** | CPU；无额外模型；需要 G4 真机 A/B。 |
| **落地步骤** | 1) 目标适配；2) 闭合触发；3) 滑移监测；4) 回退开关；5) 消融。 |
| **风险** | 坐标系/TCP 偏移；延迟；抓取层压过 VLA 语义。缓解：手眼标定、限幅、置信度门、回退。 |

### I6 · FAILURE-AUDIT：单任务通道阶段标注

| 项 | 内容 |
|---|---|
| **动机** | 没有公开真实失败分布；旧榜单是预览；必须知道失败发生在 A/B/C/D/E 哪一段，才能决定投抓取还是投插入。 |
| **与现有方案的差异** | vs 旧榜单任务排名：旧数据是脚本生成；vs 只看总成功率：阶段标注能指导工程分配。 |
| **技术可行性** | 高。单任务通道不计分；5 任务 ×10 次；视频/日志可标注。 |
| **所需资源** | 机器人时间 1–2 小时；人工标注；统计脚本。 |
| **落地步骤** | 1) baseline 5 任务；2) 标注失败阶段；3) 算 `q_t`；4) 更新任务组合；5) 决定是否投 I1–I4。 |
| **风险** | 小样本；标注噪声；任务选择偏差。缓解：配对、重复、跨任务汇总；不把 10 次当显著。 |
