## 1. 直觉与动机（两个灵感的碰撞）

### 灵感 1（步骤分 → 目标函数是稠密的、单调的、双指标的）

直觉：排行榜同时算成功率和步骤分（F20），而步骤分把「全有或全无」改写成「分段兑现」。这带来三个此前被忽略的决策：(a) **多物体任务**（FruitSorting/ColorArrangement/ArrangePlates/PickOutBatteries/ToolboxStorage）里，先搬容易的物体能更快把分装进口袋；(b) **单物体任务**在时间预算内，失败一次后「重试 vs 转向」是一个带预算的 bandit；(c) **双指标张力**：贪心刷步骤分会把时间从难里程碑挪走，最后成功率为零——步骤分高、排行榜仍可能输。核心反直觉点：**步骤分不是成功率的平滑版，而是一个独立的随机调度问题；最优策略不是「把每个任务做到最好」，而是「在时间预算内最大化期望已兑现里程碑权重，同时给成功奖励留储备」。**

### 灵感 2（共享控制 → 合规的共享不是「人机共驾」，而是「控制权在策略内部稀疏转移」）

直觉：比赛要求一个 policy class 自主完成 episode，评测期没有人会帮你；但评测里有人为干扰（PR3）。所以「共享控制」在评测期不能是人机共享，只能是两条合规路径：(a) **策略内部**多个 proposer（名义 VLA / 恢复 / 安全让位 / 视觉伺服）之间的控制权仲裁；(b) **数据生成期**的人机共享（人给粗意图、策略补细节；或 HG-DAgger 式接管纠错）。更关键的是 F21：可信度会看逐步延迟波动与动作统计规律，**连续混合（continuous blending）会制造动作抖动与延迟方差，反而先触发可信度风险**。正确形态是**事件触发、稀疏、带滞回**的切换。核心反直觉点：**共享控制的质量不由「融合得多平滑」决定，而由「干预得多稀疏、多必要」决定；最好的共享控制是大多数时候不共享，只在少数高价值时刻接管。**

### 两者统一

步骤分给出「什么时候值得接管、接管后往哪个里程碑走」的价值函数；共享控制给出「由谁执行、何时切换」的机制。合成一句：**用步骤分势函数驱动一个稀疏、事件触发的策略内仲裁器——平时让名义策略跑，只有在某里程碑的期望边际分数显著为正（或安全约束被触发）时才短暂转移控制权；训练期把仲裁行为蒸馏回单一模型，推理期只留规则安全护栏。** 数据侧则用同一势函数筛选人机纠错样本。本轮结论：**比赛的中后期胜负手从「数据更多」转向「分数兑现得更聪明」——会做不等于会得分。**

## 2. 严谨定义（先直觉后定义）

**定义 1（步骤分过程与双指标）.** 任务 τ 的计分卡 C_τ = {(m_j, w_j)}_{j=1..K}，w_j>0，Σ_j w_j=100；m_j 是里程碑谓词。轨迹 ξ 的步骤分 S_C(ξ)=Σ_j w_j·1[m_j(ξ)]；成功率 Succ(ξ)=1[∧_j m_j(ξ)]（或官方 success 谓词）。排行榜是两个泛函 (R_succ, R_step) 的聚合 g；g 未公开。因此不假设 g 的具体形式，而要求**二维不劣**：任何改动不得以步骤分增益掩盖成功率回退（PR6）。

**定义 2（进度势与联合调度）.** 已兑现势 Φ(s)=Σ_j w_j 1[m_j(s)]。剩余价值 V^π(s)=E[Σ_j w_j 1[m_j future] + B·1[success] | s,π]，B 为未知的成功奖励，用灵敏度扫描。单步调度是带先序约束的随机调度：可行里程碑 j 的分数率指数 ρ_j(s)=w_j·P_j(s)/E[t_j(s)]。若 B=0 且里程碑独立，按 ρ_j 降序的 index policy 最优（Smith/Gittins 型）；若 B>0，纯贪心会过早点完易物体，必须加入**成功储备**：为剩余最难里程碑预留时间。小 n（≤10）用子集 DP 精确求解，n 大时用 ρ 加储备阈值的近似。**双指标稳健解 = 在 g_λ=λ·Succ+(1−λ)·S/100、λ∈[0,1] 的所有 λ 下都不被固定顺序支配的策略。**

**定义 3（策略内共享控制 = 带安全掩码的切换系统）.** 提议者集合 P；每个提议者 i 给出 chunk a_i、延迟 ℓ_i、价值 Q_i(s,a)=ΔΦ+γV(s')−λ_ℓℓ_i−λ_r risk_i−λ_c‖a_i−a_prev‖。仲裁 a=argmax_{i: H(s,a_i)=1} Q_i，H 为硬安全掩码（人距、关节限、碰撞、动作界）。为避免 chattering，切换需满足 Q_i−Q_nom>δ 连续 h 个决策 epoch（滞回）。共享度 α=#switch/#decision，硬约束 α≤α_max（默认 0.1）：**共享控制是稀疏事件，不是连续混合**。训练期用该仲裁器作 scaffold 并记录 (s, proposer, a) 标签；推理期把仲裁策略蒸馏进单一网络（value head + intervention head），只保留一个规则安全掩码，保证「单模型」与低延迟方差。

**定义 4（计分卡置信度与保守势）.** 每个里程碑 m_j 的标注置信度 c_j∈[0,1]（wiki 明示=1、视频可辨=0.7、推断=0.4）。只有 c_j≥c_min 的里程碑进入 V 监督；Φ 取「已兑现」与「终态保持」两种口径的较小值，保守估计。计分卡本身是一个带置信度的假设，不是真值。

## 3. 对第 2 轮痛点的增量修订

- **P1（弱任务洼地）**：从「按任务数/难度分配」升级为「按里程碑边际分数密度分配」——弱任务的低权重里程碑可能比强任务的高权重里程碑更值得先修。
- **P3（人干扰）**：人干扰可能使 Φ **回退**（拿走已放物体/移动容器）；resume 必须重算 Φ 并重做丢失里程碑，而不是继续下一里程碑。
- **P5（时间压力）**：从「更快」升级为「在双指标下分配时间」——引入分数率、重试 bandit 与成功储备。
- **P8（示教质量）**：质量分从「平滑度/进度」升级为 **Φ 曲线下面积/时长**（单位时间兑现的分数），并显式惩罚「最后一步失败」的示教。
- **新增 P12（目标错配）**：只优化成功率会忽略可兑现的步骤分；只优化步骤分会牺牲成功率与可信度。
- **新增 P13（仲裁可信度）**：运行时切换导致延迟方差与动作统计异常，可能先于分数触发可信度审查（F21）。
- **新增 P14（计分卡不可读）**：逐任务 score_steps 仍是 JS 渲染，V 的标签来自逆向推断，必须带置信度与独立盲测。

## 4. 研究问题（本轮立项 Q9–Q12，Q1–Q8 保留）

- **Q9（步骤分可估性）**：在计分卡未公开、卡片 JS 渲染的条件下，用 wiki + 示例视频 + 自监督里程碑检测，能否得到排序可靠的 Φ？置信度如何校准？
- **Q10（联合调度）**：多物体任务的子集 DP / 成功储备阈值，相对固定顺序与纯 ρ 贪心，在 g_λ 全 λ 扫描下是否稳健占优？重试 vs 转向的阈值如何从示教估计？
- **Q11（稀疏仲裁）**：事件触发条件、滞回长度 h、干预预算 α_max 如何标定？训练期 scaffold 蒸馏到单模型后，intervention recall 能保留多少？
- **Q12（双指标注册）**：离线 ΔV 与真机 (Δsuccess, Δstep) 的二维增益如何注册与选择？何时允许为步骤分牺牲一点成功率（若 g 未知，如何用 Pareto 而非标量）？

## 5. 设计原则（新增 PR6/PR7，PR1–PR5 保留）

- **PR6 双指标不劣律**：任何改动必须在 (success, step) 二维上不劣于基线，或至少一维显著正、另一维在噪声内；禁止用步骤分增益掩盖成功率回退。
- **PR7 稀疏干预律**：运行时控制权转移必须事件触发、有滞回、α≤α_max；连续混合默认禁用，除非通过可信度与单模型合规双重审计。
- PR1–PR5 保留（第 1/2 轮 §4）。PR6 与 PR5 互补：PR5 管数据来源，PR6 管目标结算；PR7 与 PR2 互补：PR2 管模型边界，PR7 管运行时行为。

## 7. 本轮最大风险

**一句话**：步骤分计分卡与排行榜聚合公式都是逆向推断——一旦 V 的里程碑权重或 g 的形式错了，SSR 会自信地先搬易物体、把时间从难里程碑上挪走，而 SSC 的稀疏干预又让这种错误在 episode 内几乎不可见、不可纠，所以必须把「安全掩码」与「最坏 g 下不劣」作为硬门禁，V 只做排序先验、绝不做唯一真值。

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2）

> 检索日期：2026-11-26（第 1 轮）、2026-11-27（第 2/3 轮）；本轮新增 F20–F22，F1–F19 沿用。承接 v1.1：新增 I10–I12，I1–I9 增量修订。清单只增改不重置。**本轮主题：把目标从「成功率」改写为「成功率 + 步骤分」双指标，把「共享控制」从评测期人机共驾改写为「训练期脚手架 + 推理期稀疏安全护栏」。**

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I10 v1 步骤分势 + 分数率/成功储备联合调度器（SSR）★★★★★（新，目标层）

- **动机**：F20 确认排行榜是双指标；步骤分是稠密的里程碑兑现（F17）；I5/I8 的进度头只回答「做到哪了」，没有回答「下一步该做哪个里程碑 / 要不要重试 / 要不要放弃」；多物体任务（FruitSorting 等）存在明显的调度自由度（H4/H5）。
- **与现有方案差异**：现有 VLA 按固定顺序跑完整任务；I5 只在偏离后恢复；I8 只做事后消融。SSR 把步骤分从「监控信号」升级为「决策目标」：用计分卡定义 Φ/V，用分数率与成功储备决定子目标顺序、重试与放弃。
- **技术可行性**：高。
  1. **计分卡逆向**：wiki 任务描述 + 挑战页 JS 端点（待恢复）+ 官方示例视频 + 自监督里程碑检测（夹爪开合、物体-容器关系、接触事件），产出 {(m_j,w_j,pre_j,c_j)}；c_j 为置信度。
  2. **分布估计**：从 32k 示教按里程碑切段，估计每里程碑的条件时长分布 D_j(s) 与条件成功率 P_j(s)（状态特征：物体类别、位姿、遮挡、人距）。
  3. **顺序型**：按先序链执行，决策只在「重试 vs 转向（若后续独立）」；用 ρ_j=w_j·P_j/E[t_j] 与剩余时间比较。
  4. **多物体并行型**：成功需全部子任务，纯贪心会过早点完易物体（H5）；用子集 DP（n≤10）或「成功储备」阈值：先做易物体，但必须满足 `t_left − Σ已排易物体时长 ≥ E[最难剩余物体时长]`。
  5. **推理期**：V head 只在里程碑边界 / 低置信 / 重试点评估，平时不介入（与 I11 稀疏律一致）。
- **所需资源**：1×24GB GPU 做检测器与分布估计；计分卡标注 1–2 人周；DP 与 Monte Carlo 纯 CPU。
- **落地步骤**：①计分卡 v0（先 5 任务：FruitSorting/ColorArrangement/PlugCharger/PourOutMedicine/PackBag）；②从示教估 D_j/P_j；③离线 Monte Carlo 比较 fixed-order / ρ-greedy / reserve-DP 在 g_λ 全 λ 下的表现；④3 任务 L0；⑤真机 A/B（SSR on/off，固定其余模块）。
- **风险**：计分卡权重或先序错 → V 错、调度自信地跑偏（缓解：c_min 门控 + 保守 Φ + 独立盲测 + 最坏 g 不劣判据）；多物体时长估计受示教质量影响（缓解：按任务族分层估计，不用全局均值）。

### I11 v1 训练期共享控制脚手架 + 推理期单模型蒸馏（SSC）★★★★（新，机制层）

- **动机**：恢复（I5）、安全让位（I4）、接触伺服（I3）都需要「控制权转移」，但评测期不允许人机共驾；运行时多 proposer ensemble 又会碰「单模型」边界与可信度（F21：延迟波动 + 动作统计规律）。

- **技术可行性**：中-高。

- **所需资源**：1×24GB 起步；教师 rollout 数据 1 GPU 周；学生增量训练 1–2 天/轮。
- **落地步骤**：①3 任务试点（PlugCharger 接触 / FruitSorting 多物体 / PackBag 长程）；②教师仲裁器实现（先规则 Q，再学习 V）；③DAgger 采集 2–3 轮；④蒸馏 + L0（intervention recall/precision、ΔV、动作一致性）；⑤真机 A/B（SSC on/off）。

```python
    name: str; weight: float; pre: list[str]
    detect: Callable[[Any], bool]; conf: float      # c_j ∈ [0,1]

    milestones: list[Milestone]; success: Callable; T_max: float
    parallel: bool                                   # 多物体任务

def phi_banked(state, card):
    return sum(m.weight for m in card.milestones
               if m.conf >= C_MIN and m.detect(state))

def phi_final(state, card):                          # 终态保持口径
    return sum(m.weight for m in card.milestones
               if m.conf >= C_MIN and m.holds_final(state))

def phi_conservative(state, card):
    return min(phi_banked(state, card), phi_final(state, card))
```

### 2.3 训练期共享控制脚手架（I11）

```python
class SharedControlScaffold:                 # 只存在于训练/数据生成
    def __init__(self, nom, rec, safe, servo, value,
                 delta=0.05, h=3, alpha_max=0.1):
        self.p = {"nom": nom, "rec": rec, "safe": safe, "servo": servo}
        self.v, self.delta, self.h, self.alpha_max = value, delta, h, alpha_max
        self.steps = self.overrides = 0
        self.pending = None

    def act(self, s, a_prev):
        props = {k: p.act(s) for k, p in self.p.items()}
        safe = {k: a for k, a in props.items() if hard_mask(s, a)}
        q = {k: self.v.delta_phi(s, a) + self.v.gamma * self.v.V(self.v.next(s, a))
                - self.cost(k, s, a) - self.consistency(a, a_prev)
             for k, a in safe.items()}
        best = max(q, key=q.get)
        if q[best] - q["nom"] <= self.delta:       # 滞回：无显著增益不切换
            best = "nom"
        if self.overrides >= self.alpha_max * self.steps:  # 干预预算
            best = "nom"
        self.steps += 1
        self.overrides += (best != "nom")
        self.log(s, best, props[best])             # 蒸馏标签
        return props[best]

# 蒸馏目标：f_theta(s) -> (chunk, delta_V, p_intervene)
# 推理：单网络；仅 hard_mask 可否决；p_intervene 只触发掩码复核，不切换模型
```

## 3. 实验设计（分级消融协议 v3）

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0 | 计分卡 AUC；调度 Monte Carlo（fixed / ρ-greedy / reserve-DP）在 g_λ 全 λ；SSC 蒸馏 recall/precision；延迟与动作异常仿真 | 离线（免费） | 计分卡 AUC>0.9；reserve-DP 在所有 λ 不被 fixed 支配；intervention recall>0.8 |
| L1 | 2^(k-p)：SSR on/off、SSC on/off、c_min、α_max 部分析因 | 离线 + 少量真机 | 主效应显著的 ≤3 组合进入 L2 |
| L2 | 3 任务 × 2–3 次：FruitSorting（并行）/ PlugCharger（接触）/ PackBag（长程） | 单任务通道 | 双指标不劣（PR6）；p99<40ms；动作异常率 ≤ 基线 |
| 门禁 | PR4：run_client 全流程 + p99 + 动作健康度回归 | 本地 stub | 0 拒绝动作、p99<40ms |

**首批 L2 排队计划**：①SSR 离线 Monte Carlo + 1 任务真机（FruitSorting）→ ②SSC 蒸馏 3 任务（先 PlugCharger）→ ③I1 临界状态增广（背景/干扰物之后）→ ④I12 真人纠错（若遥操可得）。

**关键对照**：所有 L2 必须包含「baseline = 固定顺序 + 纯名义策略 + 无仲裁」与「仅 SSR」「仅 SSC」「SSR+SSC」四格，避免把双指标的增益归因错。
