# 第 3 轮迭代（灵感循环 v3：「柔顺控制」×「四足机器人」）—— 接触原生操作：把“看进度”升级为“摸进度”

> 承接 v2（UIP-01′~15）。本轮不做“再加一个并列模块”，而是换两条更底层的原理。**柔顺控制**说：接触不是要消除的误差，而是信息；**四足机器人**说：在欠驱动、接触密集、视觉不可靠时，靠本体感觉 + 相位 + 反射 + 全身协同活下来。迁移到 UniBot：**把机械臂当成一条会“摸”的腿**。
>
> 本轮最重要的判断：v2 的旗舰 RHPV-D 是“视觉进度”的；但 32 个任务里最值钱的步骤大多是接触主导的（插入、拧转、拉链、折叠、按压、堆叠）。视觉在这些步骤里最不可靠，而接口里恰好有一个被忽视的免费接触信号——**命令位置与观测位置的跟踪残差**。

## 0. 先给直觉：三个“以为”和三个“其实”

### 0.1 以为柔顺控制需要力传感器/力矩接口；其实位置接口也能做柔顺

- 接口没有力、力矩、电流通道；action 是位置目标（joint 或 ee），observation 是关节位置、EE 位姿、夹爪开合。没有力，但有**跟踪残差** `r = 命令位置 − 观测位置`。低层 PD 在接触时会被“顶住”：残差变大、速度变小；这就是一个**免费的、与接触力单调相关的伪触觉信号**。
- 柔顺也不必真的改低层增益：在动作空间把目标从 `q_des` 拉向 `q_obs`，即 `q_cmd = (1−λ)q_des + λq_obs`，就能让“位置目标”表现出弹簧行为。`λ=0` 是刚性，`λ→1` 是“随它去”。这在纯位置接口内可实现。
- 开环 chunk 内没有反馈？把柔顺分成两层：**chunk 边界用导纳更新**（有观测），**chunk 内用解析搜索轨迹**（螺旋、微动、拧转、拉-停-拉），后者本身就是一种开环机械柔顺。

### 0.2 以为四足机器人只是“走路”，与本赛无关；其实它是一套接触密集控制的方法论

- 腿式机器人每一步都是“接触—滑移—再接触”，和插网线、拧瓶盖、拉拉链、叠毛巾是同构问题；它们不靠每帧看清地面，而靠**本体感觉 + 相位 + 反射 + 全身协同**。
- 可迁移的四件事：① **本体感觉接触估计**（腿估计地形，我们估计接触）；② **相位化控制与相位重置**（腿的步态相位，我们的技能相位）；③ **反射**（腿的 stumble/swing reflex，我们的 stall/slip/regress reflex）；④ **全身协同**（腿的 WBC，我们的 base/pivot 宏观辅助）。
- **重要边界**：接口只暴露 `action.pivot[7]`，不暴露腿关节/腰关节动作；所以“全身”在这里只能是**base/pivot 的慢速宏观辅助**，不是动态行走或腰部力矩控制。

### 0.3 以为“柔顺”一定更好；其实柔顺有代价：会慢、会漂、会让人更容易把进度撤回

- 在自由空间，柔顺会降低有效增益、拖慢到位（1-DOF 玩具里 `λ=0.8` 的到位时间从 112ms 拉到 695ms）。
- 所以必须**相位门控 + 滞回**：自由/抓取/搬运用高刚度，插入/按压/拧转用低刚度；接触判定要带 latch，否则会在“软—硬”之间抖动（玩具里无 latch 的 `λ=0.95` 反而把峰值力打回 5.7N）。
- 人为撤回是另一类接触：机器人应“让—识别—重做”，而不是硬顶；硬顶既可能损坏物体，也可能在规则里吃亏。

## 1. 严谨定义：接口、残差、柔顺、相位、恢复

### 1.1 接口信息集（2026-11-13 核实）

记评测可见接口为 `I = (O, A, L)`：

- `O`：4 路 RGB（`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`，原生 480×640）；`left_arm[7]`、`right_arm[7]`；`left_ee_pose_gripper_base[6]`、`right_ee_pose_gripper_base[6]`；`left_gripper[1]`、`right_gripper[1]`；`lower_body[15]`；`language`（episode 常量字符串）。
- `A`：共享 `pivot[7]`、`left_gripper[1]`、`right_gripper[1]`；再二选一：`joint` 模式的 `left_arm[7]`/`right_arm[7]`，或 `ee` 模式的 `left_ee_pose_gripper_base[6]`/`right_ee_pose_gripper_base[6]`。**两种控制空间互斥，metadata 握手时定死。**
- `L`：一句任务指令，整段不变，必须在 `obs_delta_indices` 里声明为 `[0]`。
- **没有**力、力矩、电流、关节速度、手指关节通道；手只有 1 维开合。
- `action_chunk_size = T_a` 在握手时定死；每次 `get_action` 必须返回形状 `(T_a, …)` 的动作块；评测端**整块执行完**才再次调用；块内没有反馈。
- 图像经 **JPEG q95、4:4:4** 上线；N 端口并发、每端口状态隔离；**逐步延迟及其波动 + 动作统计规律性**会影响结果可信度。
- 公开数据集（抽样 PlugInEthernet：1009 episodes、30 fps、129,272 帧）比接口富：还有 `action.lower_body[15]`、`action.base_command[4]`、`action.waist_action_joint[3]`、`action.left/right_leg[6]`、`action.gripper_controls[4]`。**`I_D \ I` 是离线特权信息，不能在评测期直接使用。**
- `action.pivot[7]` 的字段名是 `[vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]`；在抽样的 PlugInEthernet 首个 parquet 上，`pivot[0:3] == base_command[0:3]`、`pivot[6] == base_command[3]` 完全相等，`pivot[3:6]` 恒为 `(0, 0.15, 0)`，**不是** `waist_action_joint` 的直接拷贝。故 `pivot` 可安全用于 base 的 `vx/vy/angle_z/height`，中间三维含义需本地探测。

### 1.2 定义 1：跟踪残差

在 chunk 边界 `t`，joint 模式定义

`r_t = W_q (q^cmd_{t-1} − q^obs_t)`，

ee 模式定义

`r_t = [ W_p (x^cmd_{t-1} − x^obs_t), W_r · Log(R^cmd_{t-1} (R^obs_t)^T) ]`。

`W` 是按关节/方向的观测噪声归一化矩阵。**残差不是力**；它只是“低层控制器被顶住”的证据。为避免把运动滞后误判成接触，必须用 1.3 的模型残差或速度门控。

### 1.3 定义 2：接触证据与滞回状态机

先用公开数据辨识一个一步预测器 `q̂_t = f_θ(q_{t-1}, v_{t-1}, a_{t-1})`，定义**模型残差**

`ρ_t = (q^obs_t − q̂_t)^T Σ^{-1} (q^obs_t − q̂_t)`。

没有辨识模型时，退化为归一化原始残差 `ρ_t = ||r_t||² / (||q^cmd_{t-1} − q^cmd_{t-2}||² + ε)`。再定义接触分数

`s_t = σ( a·(ρ_t − ρ_0) + b·(1 − v_t / v_ref) + c )`，

其中 `v_t = ||q^obs_t − q^obs_{t-1}|| / Δt`。状态机：

- `FREE`：`s_t < s_lo`；
- `CONTACT`：`s_t > s_hi` 连续 2 个 chunk；
- `STALL`：`CONTACT` 且 `v_t < v_stall` 连续 `m` 个 chunk；
- `SLIP`：夹爪开合在闭合命令下反而增大，或腕相机中物体相对夹爪位移而 `g^obs` 不变。

`s_hi > s_lo` 形成滞回；进入/退出都要连续计数，禁止单帧翻转。**没有滞回，柔顺会在软硬之间抖动，稳态力反而回升**（见产物区 §11 的玩具结果）。

### 1.4 定义 3：离散导纳

在 chunk 边界，令

`q^cmd_i = (1 − λ_t) q^des_i + λ_t q^obs_t`，`i = 0..T_a−1`，

其中 `λ_t = λ_max · m_t`，`m_t ∈ {0,1}` 由相位与接触状态给出。等价地，`q^cmd` 是“期望目标”和“当前实测”的凸组合。1-DOF 准静态推导给出有效刚度

`k_eff = k_e (1−λ) / ((1−λ) + k_e/k_p)`，

当环境很硬（`k_e ≫ k_p`）时 `k_eff ≈ k_p(1−λ)`。这就是“位置接口上的柔顺”：不改变低层 PD，只改变目标。

**边界条件**：`0 ≤ λ ≤ 0.85`；加包络 `|q^cmd − q^obs| ≤ δ_max`；加变化率限制，避免动作统计异常。`λ` 不是越大越好；`λ→1` 会失去位置 authority，导致“软而不到位”。

### 1.5 定义 4：相位化技能与相位重置

一个技能 `π_k` 是带关键帧的轨迹

`π_k = {(φ_j, q_j, g_j)}_{j=0..K−1}`，`0 = φ_0 < … < φ_{K−1} < 1`，

执行时 `φ_{t+1} = φ_t + Δφ`。受到干扰时，不做“整段重来”，而是找最后一个已完成关键帧 `j = max{φ_j ≤ φ_t}`，执行**相位重置**

`R_ε(φ) = max(0, φ_j − ε)`。

若干扰是“已完成的计分步被撤回”，则重置到该计分步的起始关键帧。恢复代价从“重做剩余全部阶段”降为“重做 1 个关键帧段”。

### 1.6 定义 5：按原因恢复（Cause-Aware Recovery）

接触不是一种状态，而是多种原因。定义原因集合

`C = {FREE, ENV_CONTACT, ENV_STALL, SLIP, HUMAN_REGRESS, BASE_PUSH}`。

每个原因对应证据 `e(c)` 与恢复原语 `ρ(c)`：

| 原因 | 主要证据 | 恢复原语 |
|---|---|---|
| `ENV_CONTACT` | 残差高、速度低、处于接触相位 | 导纳保持 + 小步搜索 |
| `ENV_STALL` | 残差高、进度为零、超时 | 后退 `δ` → 重新对齐 → 螺旋搜索 → 再插入 |
| `SLIP` | 夹爪开合异常增大 / 物体相对夹爪位移 | 加闭合力 → 重新抓取 → 重做该子目标 |
| `HUMAN_REGRESS` | 已完成子目标谓词回退 / 物体逆命令方向移动 | 让力（降刚度）→ 重新定位 → 相位重置重做 |
| `BASE_PUSH` | `lower_body` 腿/腰状态异常、非命令基座运动 | 暂停 → 用 pivot 高度/位置微调支撑 → 重做 |
| `FREE` | 残差低、速度高 | 正常高刚度执行 |

**关键区别**：`ENV_STALL` 要“搜索着进”，`HUMAN_REGRESS` 要“让开再重做”。把两者都叫“重试”会浪费步骤分。

### 1.7 定义 6：开环接触搜索原语

在局部接触坐标系 `(e_1, e_2, e_z)` 中，围绕估计的孔/口位置 `p̂` 生成

`p(τ) = p̂ + A(τ)[cos(ωτ + φ_0) e_1 + sin(ωτ + φ_0) e_2] + v_z τ e_z`。

- 向外搜索：`A(τ) = A_0 · τ/T`（阿基米德螺旋）；
- 向内搜索：`A(τ) = A_0 · exp(−τ/τ_a)`（指数收敛）。

若孔半径与插头半径之差为 `c`，螺旋每圈径向间距 `Δr ≤ 2c` 时，路径会扫过以真值中心为圆心、半径 `c` 的圆盘，因而**在运动学意义上保证覆盖**。圈数 `N ≈ R/Δr`，搜索时间 `T ≈ 2πN/ω`。

**开环 chunk 内的连续性**：把 `θ = ωτ` 与 `p̂` 存进 policy 的 per-port 状态；chunk 边界只更新 `p̂` 和相位，不重置 `θ`，除非检测到新的接触/滑移。这样搜索可以跨 chunk 连续执行，不需要块内反馈。

### 1.8 定义 7：base/pivot 宏观辅助（严格受限）

`pivot[7]` 可命令 `vx, vy, angle_z, height`（中间三维待探测）。只允许**准静态、小幅度、限速率**的 base 调整，用于：

1. 把物体带到舒适工作空间（减少腕部极限）；
2. 在接触前做宏观对位；
3. 在受到大扰动时，用 base 的微小退让吸收冲量。

**不假设**动态行走、不假设腰部关节可命令、不假设 base 不会被评测端 clamp。先做探针实验；若 `pivot` 被 clamp，UIP-18 退化为可选，不影响旗舰。

### 1.9 定义 8：控制空间的一次性决策门

`joint` 与 `ee` 互斥，metadata 只能握手一次。两者都能算残差（joint 用关节，ee 用笛卡尔），但：

- `joint` 与公开数据集的 `action.left/right_arm` 完全同构，模仿学习最直接；能直接做逐关节限位与导纳；
- `ee` 的任务空间残差更直观，但需要内部 IK，残差会混入 IK 误差。

v3 默认选 `joint`；若 GSO/真机显示 `ee` 明显更好，再在提交前切换。**这不是运行期仲裁**，v2 的 UIP-10 仍然封存。

## 2. 为什么现在做：接触步是高分步，也是数据最空白的步

- 32 任务中至少 17 个含明确的接触关键步：T05 拔网线、T09 工具箱、T10 插插头、T11 电池、T12 开锁、T14 倒药、T16 叠毛巾、T17 文具盒、T18 书包拉链、T19 拉链、T23 球拍、T25 纸杯、T26 插网线、T27 叠碗、T29 手机壳、T31 笔袋、T32 针管。
- 这些步骤的共同点：**视觉被手/物体遮挡、位置控制容易卡死、失败往往发生在最后一步（末步分值恒 ≥ 前序步）**。
- v2 的 `human_*` 证据表明：人为干扰大量是“把已完成进度反向撤回”。撤回通常通过接触实现（拉、拧、拿、翻）。因此“接触感知 + 柔顺 + 按原因恢复”同时命中**环境接触**与**人为撤回**两条轴。
- 公开数据里没有“扰动—恢复”演示，但有大量**正常接触**演示；正常接触足以辨识低层 PD/延迟，也足以学习“接触时应该多软”。这是本轮相对 v2 的新数据杠杆。

## 3. 瓶颈假设

- **H1（最高杠杆）**：接触密集步的主要瓶颈不是语义，而是**位置控制太硬**：插不进、拧不动、拉链卡住、叠放弹开。动作空间导纳能直接降低接触力峰值与卡死概率。
- **H2**：跟踪残差是可用的接触代理，但会被运动滞后、重力、摩擦污染；必须用公开数据辨识低层模型，做**模型残差**而不是裸残差。
- **H3**：人为撤回与环境卡滞是不同原因；恢复策略必须**按原因**选择“搜索着进”还是“让开重做”，否则会浪费步骤分。
- **H4**：相位重置比整段重来省时间；任务越长、干扰越频繁，收益越大。30% 的恢复时间下降在固定时限下等价于更多任务能完成。
- **H5**：`pivot` 的 base 辅助可能被 clamp；它只能是加分项，不能是旗舰的单点依赖。
- **H6**：柔顺的调参对低层 PD/延迟/接触刚度极敏感；没有 ACDR（执行器/接触域随机化）与真机锚点，GSO 上的最优 `λ` 很可能在真机上翻车。

## 4. 候选与合并 → v3 清单

围绕两个词发散 8 个草案，合并后得到 v3：**新增 5 个（UIP-16~20）、升级 7 个、合并 1 个（UIP-09′ → UIP-19）、保持封存 2 个（UIP-04、UIP-10）**。旗舰从 v2 的“视觉滚动验证”升级为 **CNM（Contact-Native Manipulation，接触原生操作）**：

- **UIP-16 PACL**：本体感觉导纳与接触层（旗舰）；
- **UIP-17 CSP**：接触搜索原语 + 相位化技能；
- **UIP-19 PRR**：按原因恢复反射（吸收 UIP-09′）；
- **UIP-18 WBA**：base/pivot 宏观辅助（可选）；
- **UIP-20 ACDR**：执行器/接触域随机化 + 公开数据辨识。

三条腿支撑旗舰：**PACL 把接触变成可观测的量，CSP 把接触步变成可执行的搜索，PRR 把失败变成有方向的恢复**。v2 的 GSO/DRF/ACS/MSGR/CSG 全部保留，但都要加上“接触相位”这一维。

## 5. 本轮最大风险

**一句话最大风险：跟踪残差不是力，开环搜索也不是闭环；若不在公开数据上辨识低层 PD/延迟、不用 GSO/真机校准门控与 `λ`，PACL 会把“柔顺”做成“迟滞”，在最后一步丢掉最高分值；更糟的是，过度软化会让抓取/搬运也失败。**

**→ 本轮最值得押注：UIP-16 PACL × UIP-17 CSP × UIP-19 PRR 组成的 CNM 闭环**——它把 v2 的“看得见的进度”升级为“摸得着的进度”，精确对准接触密集的高分步，且全部落在位置接口、单模型与选手算力之内。

## 3. 旗舰深潜：UIP-16 PACL（Proprioceptive Admittance & Contact Layer）

### 3.1 机制

PACL 是夹在主策略与评测端之间的**确定性控制层**，不是第二个模型：

1. 在 chunk 边界用 `q^cmd` 与 `q^obs` 算跟踪残差 `r_t`（joint 或 ee 空间）；
2. 用 AID（UIP-20）的模型残差或原始残差 + 速度门控，得到接触证据 `s_t`；
3. 用滞回状态机判定 `FREE / CONTACT / STALL / SLIP`；
4. 按技能相位给出 `λ_t`，把主策略的动作块整体拉向当前实测：
   `q^cmd_i = (1−λ_t) q^des_i + λ_t q^obs_t`；
5. 若 `STALL/SLIP`，交给 UIP-19 选择恢复原语；若 `FREE`，`λ=0`，完全听主策略。

**为什么是凸组合而不是“降低增益”**：接口只能发位置目标，无法改低层 PD。把目标拉向实测，等价于在目标空间引入一个虚拟弹簧；`λ` 就是“软硬旋钮”，不需要任何额外接口。

### 3.2 1-DOF 推导（准静态）

设低层 PD 把关节拉向 `q^cmd`，环境是刚度 `k_e` 的弹簧（墙在 `q=0`）：

- 力平衡：`k_p(q^cmd − q) = k_e q`；
- 导纳目标：`q^cmd = q^des + λ(q − q^des)`；
- 代入：`k_p[(1−λ)(q^des − q)] = k_e q`；
- 解得：

```text
q = (1−λ) q^des / [(1−λ) + k_e/k_p]
F_env = k_e q = k_e (1−λ) q^des / [(1−λ) + k_e/k_p]
k_eff = F_env / q^des = k_e (1−λ) / [(1−λ) + k_e/k_p]
```

当 `k_e ≫ k_p` 时 `k_eff ≈ k_p(1−λ)`。这解释了玩具结果：`k_p=200`、`k_e=2000`、`q^des=0.02m`、`λ=0.8` 时，`F≈0.784N`；`λ=0.5` 时 `F≈1.905N`，与仿真吻合。

### 3.3 接触证据：裸残差 vs 模型残差

**裸残差**的致命问题：自由空间加速时 `q^cmd − q^obs` 也会很大，容易被误判为接触。三个修正：

1. **速度门控**：接触时“命令在动、实际几乎不动”；自由空间“命令和实际都在动”。用 `v_t` 做门控。
2. **模型残差**：用公开数据辨识 `q̂_t = f_θ(q_{t-1}, v_{t-1}, a_{t-1})`，只把“模型也解释不了的偏差”当接触证据。这能扣掉重力、摩擦、正常跟踪滞后。
3. **滞回 + 连续计数**：进入 `CONTACT` 要连续 2 个 chunk 超上阈值，退出要连续 3 个 chunk 低于下阈值；禁止单帧翻转。

```python
# UIP-16: 接触证据与滞回（示意）
def contact_state(obs, cmd_prev, model, st, cfg):
    q, qd = obs["q"], obs.get("qd", finite_diff(obs))
    r = cmd_prev - q
    rho = model.mahalanobis(q, qd, cmd_prev) if model else norm(r)**2 / (norm(st.dq_cmd_prev)**2 + 1e-9)
    v = norm(q - st.q_prev) / cfg.dt
    s = sigmoid(cfg.a*(rho - cfg.rho0) + cfg.b*(1 - v/cfg.v_ref) + cfg.c)
    # 滞回 + 连续计数
    if st.state == "FREE" and s > cfg.s_hi:
        st.hi_count += 1
    elif st.state != "FREE" and s < cfg.s_lo:
        st.lo_count += 1
    else:
        st.hi_count = st.lo_count = 0
    if st.state == "FREE" and st.hi_count >= 2:
        st.state, st.hi_count = "CONTACT", 0
    elif st.state in ("CONTACT", "STALL") and st.lo_count >= 3:
        st.state, st.lo_count = "FREE", 0
    if st.state == "CONTACT" and v < cfg.v_stall and st.progress == 0:
        st.state = "STALL"
    return st.state, s
```

### 3.4 相位化柔顺 profile

| 相位 | `λ` | 目的 | 备注 |
|---|---:|---|---|
| `REACH` | 0.0 | 快速到位 | 高刚度，避免“软而慢” |
| `GRASP` | 0.0–0.2 | 夹稳 | 闭合过程中不要软，否则夹不住 |
| `TRANSPORT` | 0.0 | 保持位姿 | 高刚度 |
| `ALIGN` | 0.2–0.5 | 慢速对位 | 允许小幅让力 |
| `CONTACT/INSERT` | 0.6–0.85 | 插入/按压/拧转 | **只在接触相位打开** |
| `RELEASE/RETREAT` | 0.0 | 干净退出 | 高刚度，快速离开 |

**关键**：柔顺不是全程打开。抓取和搬运阶段软化 = 丢物体；插入和按压阶段硬化 = 卡死/大冲击。

### 3.5 玩具结果：1-DOF 接触（明确标注为玩具）

模型：质量-弹簧-阻尼 + 墙；`m=0.5`、`k_p=200`、`k_d=10`、`k_e=2000`、`q^des=0.02m`、控制 100Hz、低层 1kHz；目标轨迹用 0.3s smoothstep 平滑接近（避免“瞬移目标”造成的虚假峰值）。`phase` = 接近目标 60% 后提前打开柔顺；`gated` = 只在检测到接触后打开。

| 配置 | 稳态接触力 | 峰值接触力 | 自由空间到位 95% |
|---|---:|---:|---:|
| 刚性 `λ=0` | 3.636 N | 3.688 N | 308 ms |
| `λ=0.5` 相位门控 | 1.905 N | 1.939 N | 337 ms |
| `λ=0.8` 相位门控 | 0.784 N | 0.829 N | 422 ms |
| `λ=0.95` 相位门控 | 0.199 N | 0.526 N | 1154 ms |
| `λ=0.8` 仅接触后门控 | 0.784 N | 0.829 N | 860 ms |

**读法**：

- `λ=0.8` 是甜点：力降约 78%，到位只慢约 37%；
- `λ=0.95` 力更低，但自由空间明显变慢，且更容易“软而不到位”；
- 相位门控（接触前就逐渐软化）比“接触后才软化”到位更快（422ms vs 860ms），因为它提前降低了接近速度/冲击；
- **无滞回会抖动**：在同一玩具的“瞬移目标”版本里，无 latch 的 `λ=0.95` 稳态力从 0.199N 回升到 2.009N、峰值仍 5.7N；这就是为什么 §3.3 必须做滞回。

> 这些是玩具数值，不是真机力；它们只用于验证公式和门控逻辑，不能直接外推到 G1。

### 3.6 PACL 的边界

- 残差不是力；重物、重力补偿误差、关节摩擦、回差都会污染它；
- 位置误差在自由空间也可能很大；必须有速度门控或模型残差；
- `λ` 太高会失去位置 authority，导致“到不了目标”；
- 评测端如果对动作做低通/限幅，导纳效果会被削弱；必须用 GSO/真机确认；
- 单模型合规：PACL 是控制律，不是模型；若学习接触分类器，必须是共享骨干上的小头，不能是外部 VLM。

### 4.2 螺旋覆盖的严谨条件

阿基米德螺旋 `A(τ)=A_0 τ/T`，每圈径向间距 `Δr = 2π A_0 / (ω T)`。若孔-轴间隙为 `c`，当 `Δr ≤ 2c` 时，螺旋路径会扫过以真实孔心为圆心、半径 `c` 的圆盘（运动学覆盖）。圈数 `N ≈ R/Δr`，搜索时间 `T ≈ 2πN/ω`。

玩具蒙特卡洛（3,000 次，初始横向误差在 2mm 圆盘内均匀，`c=0.2mm`）：

| 策略 | 运动学成功率 |
|---|---:|
| 刚性直插 | 1.06% |
| 螺旋搜索（Δr=2c） | 95.60% |

> 95.6% 而非 100% 是离散采样/圈数截断造成的；加密路径、增加圈数或加 admittance 可继续提高。该模型只算几何覆盖，不含接触动力学，因此是“上界示意”，不是真机成功率。

**相位重置 vs 整段重来**（蒙特卡洛，200,000 次）：

- 设定：5 个阶段、每阶段 0.6s、chunk=4 步 @30Hz、干扰在 episode 内均匀发生、在下一个 chunk 边界检测；
- 整段重来：从当前阶段重做剩余全部阶段；
- 相位重置：只重做最后一个关键帧段（1 阶段 + 0.2s 稳定）；
- 结果：平均剩余时间 **1.868s → 1.307s，减少 30.1%**。

> 该结果只衡量“重做时间”；真实步骤分还取决于干扰是否已把该步判为失败。但“少重做”在固定时限下等价于更多任务能完成。

## 5. UIP-19 PRR：按原因恢复反射

### 5.1 状态机

```text
FREE ──(s>s_hi, 2 chunks)──> CONTACT ──(v<v_stall, progress=0)──> STALL
  ↑                              │                                  │
  │                              └──(gripper opens / object slips)──> SLIP
  │                                                                  │
  └──(s<s_lo, 3 chunks)──────────────────────────────────────────────┘
任意状态 ──(已完成子目标谓词回退 / 物体逆命令移动)──> HUMAN_REGRESS
任意状态 ──(lower_body 异常 / 非命令基座运动)──────> BASE_PUSH
```

### 5.2 原因 → 恢复原语

```python
# UIP-19: 按原因恢复（示意）
def recover(cause, task, phase, skill):
    if cause == "ENV_STALL":
        return ["RETREAT", "REALIGN", "SPIRAL", "REINSERT"]
    if cause == "SLIP":
        return ["REG_RASP", "REDO_SUBGOAL"]
    if cause == "HUMAN_REGRESS":
        return ["YIELD", "RELOCALIZE", "PHASE_RESET"]
    if cause == "BASE_PUSH":
        return ["PAUSE", "PIVOT_BRACE", "REDO_SUBGOAL"]
    return []
```

### 5.3 为什么必须区分 `STALL` 与 `HUMAN_REGRESS`

- `ENV_STALL`：机器人自己推不动环境；正确动作是**换着法子进**（后退、对位、螺旋、拧转）。
- `HUMAN_REGRESS`：人把进度撤回了；正确动作是**让开、看清、重做**，而不是继续在旧位置硬推。
- 把两者都当“重试”，会导致：对 `STALL` 反复硬顶（力大、损坏、超时）；对 `HUMAN_REGRESS` 在空位置空推（浪费步骤分）。
- 证据区分：`HUMAN_REGRESS` 通常伴随“已完成子目标谓词从 done 回退”或“物体逆命令方向大幅移动”；`ENV_STALL` 通常发生在接触相位、物体不动、机器人自己在推。

### 5.4 与 v2 RHPV-D 的关系

v2 的 `regressed` 是一个布尔状态；v3 把它拆成**原因 + 恢复原语**。RHPV-DC（UIP-01″）在 chunk 边界同时做两件事：

1. 视觉/几何验证器判断子目标 `done/ongoing/fail/regressed`；
2. PACL 判断接触状态 `FREE/CONTACT/STALL/SLIP`。

两者交叉得到 §5.2 的原因；恢复由 PRR 执行，进度由 RHPV-DC 继续核验。这样“看得见”和“摸得着”互为补充。

## 6. UIP-18 WBA：base/pivot 宏观辅助（可选）

### 6.1 能做什么

`pivot[7]` 的 `vx, vy, angle_z, height` 可用于：

- **对位**：把物体带到双臂舒适工作空间，减少腕部极限；
- **高度**：桌面高度不匹配时，用 `height` 小幅调整；
- **让力**：受到大扰动时，base 小幅后退/侧移，吸收冲量，而不是让手臂硬顶；
- **可达性**：远/边物体先 base 靠近，再伸臂。

### 6.2 不能做什么

- 不能命令腿关节/腰关节（接口不暴露 `action.lower_body`/`action.waist_action_joint`）；
- 不能假设动态行走或平衡恢复；
- 不能假设 `pivot` 一定生效（可能被评测端 clamp）；
- 不能把 base 运动当作快速反射（base 响应慢、观测不足）。

### 6.3 探针实验（第一周）

在本地 `example_env.py` 或 Gazebo 中：

1. 发 `pivot = [0.02, 0, 0, 0, 0.15, 0, h0]` 持续 0.5s，观察 `lower_body`、EE 位姿、腕相机场景位移；
2. 发 `height` 阶跃 ±1cm，观察 `lower_body` 与相机高度；
3. 发 `angle_z` 阶跃 ±2°，观察 base 朝向；
4. 若以上均无变化 → `pivot` 被 clamp，UIP-18 降级为“只记录不用”。

**决策门**：若探针显示 base 可控，UIP-18 作为“远/边任务”的加分项；若不可控，不影响 CNM 旗舰。

## 7. UIP-20 ACDR：执行器/接触域随机化 + 公开数据辨识

### 7.1 从公开数据辨识低层模型

公开数据有 `(q_t, a_t, q_{t+1})`，足以拟合一个一步预测器。用简单的离散模型：

```text
q_{t+1} = A q_t + B v_t + C a_t + d + ε_t
v_t = (q_t − q_{t-1}) / Δt
```

按关节做 ridge 回归；用 held-out episode 验证。更好的版本是带 PD 结构的模型：

```text
v_{t+1} = v_t + Δt [ K_p (a_t − q_t) − K_d v_t − F_f(v_t) + g(q_t) ] / M + ε
```

拟合 `K_p, K_d, M, F_f` 与执行延迟 `d`（用互相关找最佳 lag）。这一步的价值：

- 给 PACL 一个**模型残差**，而不是裸残差；
- 给 GSO 一个**数据驱动的低层控制器**，而不是假设理想 PD；
- 给 `λ` 一个**真机可比的校准基准**。

### 7.2 在 GSO 中随机化

| 参数 | 范围（待真机校准） | 目的 |
|---|---|---|
| 接触刚度 `k_e` | 200–5000 N/m | 覆盖软物体到硬塑料 |
| 摩擦系数 `μ` | 0.2–1.0 | 覆盖光滑/粗糙 |
| 执行器延迟 | 0–60 ms | 覆盖网络/低层延迟 |
| PD 增益 | ±30% | 覆盖不同机器/批次 |
| 物体质量 | ±50% | 覆盖未见物体 |
| 关节摩擦/回差 | 数据辨识分位数 | 覆盖 G1 个体差异 |

**原则**：GSO 只当“结构/顺序/接触相位”的裁判，不当“像素级成败”的裁判（承接 v2 H4）。ACDR 的目的是让“结构裁判”在真机上仍然成立，而不是在仿真里刷分。

## 8. 对 v2 清单的升级

### 8.1 UIP-01″ · RHPV-DC

- 原 RHPV-D：每 k 步视觉/几何验证子目标，`done/ongoing/fail/regressed`。
- 升级：在 chunk 边界并联 PACL 的接触状态；`regressed` 拆成 `ENV_STALL/SLIP/HUMAN_REGRESS/BASE_PUSH`；恢复交给 PRR；恢复后**相位重置**而不是从头重来。
- 伪代码见 §9。

### 8.2 UIP-11′ · GSO-A

- 加执行器模型（§7.1）、接触标签（GSO 内部真值）、接触力代理（关节残差/接触力）；
- 用 GSO 给 PACL 的 `λ`、阈值、搜索参数做离线网格搜索；
- 输出不只是“成功率”，还有“峰值接触力代理、卡滞次数、恢复时间”。

### 8.3 UIP-12′ · DRF-C

- 造三类数据：① 正常接触（插入/拧转/拉链/折叠/按压）；② 环境卡滞（孔偏移、摩擦大、物体软）；③ 人为撤回（拉走、拧回、翻开、拉开、拿走）；
- 对每类生成“失败—检测—恢复”三元组；恢复轨迹用 CSP 原语脚本化；
- 用 ACDR 随机化接触/执行器参数，避免“只学会一种刚度”。

### 8.4 UIP-13′ · ACS-T（纠正 v2 的“运行期变长”假设）

v2 UIP-13 假设“每次可返回 ≤k 步的块”；但 README §3 要求形状 `(T_a, …)`，**运行期返回更短的块可能被拒**。v3 改为**固定 `T_a` + 安全尾**：

```text
A = (A_head, A_tail)
A_head: 执行当前技能的前 T_h 步（推进）
A_tail: 收缩/保持/搜索/后退（不可造成不可逆失败）
T_h + T_tail = T_a（固定）
```

- 自由空间：`T_h = T_a`，无安全尾；
- 接触相位：`T_h` 小（2–4 步），`A_tail` 是导纳保持 + 小搜索；
- 这样即使块内发生接触/扰动，剩余步也不会继续“硬推”；
- 安全尾必须从 `A_head` 最后一步平滑过渡，避免动作跳变（可信度）。

### 8.5 UIP-14′ · MSGR-C

- 技能图节点从“抓/放/插/…”升级为“技能 + 相位 + 柔顺 profile + 恢复原语”；
- 每个节点携带 `λ(φ)`、`A_tail` 类型、`recovery(cause)`；
- 路由仍由语言 + 首帧决定，单骨干 + 技能头，合规不变。

### 8.6 UIP-15′ · CSG-C

新增四类护栏：

1. `λ` 上限与变化率限制（防抖动）；
2. 接触力代理上限（`ρ` 超限→后退）；
3. 安全尾最大持续时间/最大重试次数；
4. 动作平滑/限幅（防可信度异常）。

## 9. 关键算法伪代码

```python
class CNM_Policy:  # UIP-01″ + 16 + 17 + 19 + 13′ + 15′
    def __init__(self, base_policy, verifier, skill_graph, contact_model,
                 cfg):
        self.p = base_policy
        self.v = verifier
        self.g = skill_graph
        self.cm = contact_model
        self.cfg = cfg

    def reset(self):
        self.p.reset()
        self.st = ContactState()          # q_prev, cmd_prev, latch counters
        self.subgoal = 0
        self.phase = 0.0
        self.redo = 0
        self.search = SearchState()       # p_hat, theta, active

    def get_action(self, obs):
        # 1) 视觉/几何进度验证（v2 RHPV-D）
        prog = self.v(obs, self.subgoal)  # done/ongoing/fail/regressed
        # 2) 本体接触证据（UIP-16）
        cause = self.cm.update(obs, self.st)
        if prog == "regressed":
            cause = self.cm.classify_regression(obs)  # HUMAN_REGRESS / BASE_PUSH
        # 3) 相位与柔顺 profile
        lam = self.g.lambda_at(self.subgoal, self.phase, cause)
        # 4) 需要恢复？
        if cause in ("ENV_STALL", "SLIP", "HUMAN_REGRESS", "BASE_PUSH"):
            prim = self.g.recovery(cause, self.subgoal)
            self.phase, self.subgoal = self.g.reset_phase(
                self.phase, self.subgoal, cause)
            return self._recovery_chunk(obs, prim, lam)
        # 5) 主策略 + 导纳 + 安全尾（UIP-13′）
        Ta = self.cfg.action_chunk_size
        q_des = self.p.get_action(obs)              # (Ta, ...)
        head, tail = self.g.split_head_tail(self.phase, cause, Ta)
        q_cmd = self.g.render(self.phase, head, tail, obs)
        q_cmd = self._admittance(q_cmd, obs, lam)   # 凸组合 + 包络
        q_cmd = self._smooth_and_clip(q_cmd)        # CSG-C
        # 6) 推进相位/子目标
        self.phase = self.g.advance(self.phase, Ta, cause)
        if prog == "done":
            self.subgoal += 1; self.redo = 0
        return self._pack(q_cmd)

    def _admittance(self, q_des, obs, lam):
        q_obs = obs["q"]
        q_cmd = (1.0 - lam) * q_des + lam * q_obs
        # 包络：不要把目标拉得离实测太远/太近
        return clip(q_cmd, q_obs - self.cfg.delta_max,
                           q_obs + self.cfg.delta_max)

    def _recovery_chunk(self, obs, prim, lam):

        # 关键：恢复块也必须是 (T_a, ...)，且首步与上一条动作连续
        ...
```

**与接口的硬约束对齐**：

- 所有动作数组必须是 `(T_a, …)`；不能用“返回更短块”实现反应性；
- `reset()` 每 episode 一次，必须清空 per-port 的接触/相位/搜索状态；
- 多端口共享模型时，`st/phase/search` 必须按端口隔离；
- 动作要平滑、限幅、无异常 outlier（可信度）。

### 11.1 1-DOF 接触：导纳 + 相位门控

## 12. 合规、风险与决策门

### 12.1 合规

- **单模型**：PACL/CSP/PRR 是确定性控制律/轨迹生成器，不是第二个模型；若学习接触分类器，必须是共享骨干上的小头，不能是外部 VLM。
- **接口**：所有动作形状 `(T_a, …)`；`reset()` 清状态；N 端口状态隔离；动作平滑、限幅。
- **推理期**：不调用外部大模型；语言仍只在 episode 开始时解析一次（承接 v2/v3 语言方案）。
- **可信度**：柔顺/搜索轨迹必须平滑；禁止高频抖动、异常 outlier、块边界跳变。

### 12.2 主要风险

1. **残差 ≠ 力**：重力、摩擦、回差、运动滞后都会污染；必须用 AID 模型残差 + 速度门控 + 滞回。
2. **柔顺过度**：抓取/搬运阶段软化会丢物体；必须相位门控，只在接触/插入/按压阶段打开。
3. **开环块内无反馈**：块内只能靠解析搜索/安全尾；真正的反馈只在 chunk 边界。
4. **`pivot` 可能被 clamp**：UIP-18 只能是加分项，不能是旗舰单点。
5. **仿真过拟合**：GSO 的接触/执行器参数不真，最优 `λ` 可能翻车；必须 ACDR + 真机锚点。
6. **人为撤回 vs 环境卡滞误判**：会导致“该让开时硬顶/该搜索时空推”；必须按原因恢复，并允许保守回退到 v2 的视觉验证。

### 12.3 决策门（kill criteria）

| 门 | 条件 | 行动 |
|---|---|---|
| G0 控制空间 | `joint` vs `ee` | 默认 joint；若 GSO/真机 ee 明显更好，提交前切换 |
| G1 接触观测 | E202 AUROC <0.8 | 放弃 PACL 主导，回退到 v2 视觉 RHPV-D |
| G2 base | E205 pivot 被 clamp | 关闭 UIP-18，只保留手臂柔顺 |
| G3 甜点 | E201 `λ=0.8` 在 GSO 力降 <30% | 重新辨识 PD/延迟，或改用 ee 空间导纳 |
| G4 可信度 | 动作抖动/延迟方差显著变差 | 降低 `λ`、加平滑、减少搜索频率 |

**→ 押注：UIP-16 PACL × UIP-17 CSP × UIP-19 PRR 的 CNM 闭环**——用跟踪残差当免费接触观测器，用相位化柔顺原语过接触密集步，用按原因恢复 + 相位重置从人为撤回中恢复；它把 v2 的“看得见的进度”升级为“摸得着的进度”，且全部在位置接口、单模型与选手算力之内。

**一句话最大风险：跟踪残差不是力，开环搜索也不是闭环；若不在公开数据上辨识低层 PD/延迟、不用 GSO/真机校准门控与 `λ`，PACL 会把“柔顺”做成“迟滞”，在最后一步丢掉最高分值；过度软化还会让抓取/搬运一起失败。**
