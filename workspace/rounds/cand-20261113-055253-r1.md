# 第 1 轮（灵感循环 v3 · 承接 v2）：「通信延迟」×「视觉语言模型」——把远程回路当作"有延迟的语义信道"

> **本轮不是给 v2 再加一个验证器，而是换一个物理层的视角重写它。** v2 已把"人为干扰=把已完成进度反向撤回"确立为规则级事实，并把旗舰定为 **UIP-01′ 滚动验证-重做**。但 v2 隐含了一个未经检验的假设：验证器可以在需要时立刻给出答案。远程部署恰恰相反——图像要经 JPEG/网络传到策略侧，VLM 推理又要时间，评测端却已经按开环块把动作执行完了。于是本轮的核心问题变成：**在"观察—判断—动作"各自有延迟的回路里，语义验证还来不来得及救分？** 本轮两个灵感词给出的答案不是"更强的 VLM"，而是 **把 VLM 的语义能力拆成"离线教师 + 在线快头"，把通信延迟拆成"可设计的观测集 + 可设计的块长与块内风险形状"**。一句话：**延迟不是可信度指标，它首先是步骤分的自变量；VLM 不是越大越好，而是越"赶得上"越好。**

### 0.2 两条必须写进设计的"接口红线"（对 v2 的修正）

1. **v2 的 UIP-13 假设"每次可返回 ≤k 步"不成立。** 官方要求每次返回**恰好 T_a 步**，且 `metadata` 在连接握手时固定。因此"按阶段实时改块长"只能在**握手期选择**（若评测按任务重连，才可能逐任务特化），运行期不能改。真正可做的是：**握手期选一个 T_a，运行期设计块内动作的风险形状**（见 UIP-18）。
2. **运行期不能按步"少收"观测。** 一旦在 metadata 里声明了某键，评测端每次都会发送它；想省带宽必须在**握手期**选最小观测集（以及分辨率/堆叠），不能临时少收。因此"语义压缩"是一个**离线设计 + 全局鲁棒配置**问题，不是在线调度问题。

> 这两条修正把本轮的"实时性"从"运行期调参"逼成了**握手期的延迟-块长-载荷联合设计**——反而更适合用严谨的约束优化来写。

### 0.3 沿用 v2 的事实（不重复检索，仍按 2026-11-12 记录）

- 计分 = **平均成功率 + 步骤分**；每任务 100 分，末步权重恒 ≥ 前序步。
- `generalization.human_*` 大量是**反向撤回**：T12 中途把锁拿走、T14 拧回、T16 翻开、T17 合上再打开、T19 拉上再拉开、T27 叠好再拿下。
- 至少 11 个任务存在明确撤回型干扰；公开数据零覆盖。
- `action_chunk_size` 是开环执行下唯一的"重观测频率"旋钮；JPEG 堆叠帧数直接抬延迟。
- 合规 = **单模型多任务**；外部 VLM 在推理期可能被判"非单模型"。

## 1. 先给直觉：这是一个"慢眼睛 + 快肌肉"的问题

想象你在远程操控一只机械手，但你看到的是**几百毫秒前的画面**，而你发出的动作会**一口气执行好几步**。这时会发生三件事：

1. **你看到的不是现在。** 你看到杯子还在桌上，实际上人已经把它拿走了；你的动作基于"旧世界"。
2. **你的判断比动作慢。** 语言模型能看懂"拉链被拉开了"，但从上传图像到它回答，可能已经过去 100–1000 ms；这期间机械手还在按旧计划走。
3. **你不能一直高清多帧地盯着。** 4 路 480×640、每路再堆 2 帧，就是 8 张 JPEG；在上行带宽只有几 Mbps 时，光上传就可能几百毫秒。相反，43 个 float 的状态堆 8 帧只有约 1.4 KB，几乎免费。

所以真正的设计变量不是"用不用 VLM"，而是：

> **把多少毫秒的语义延迟，摊到多长的动作块上；以及在块内，把哪些不可逆动作放在观测最新鲜的位置。**

这给出一条与 v2 不同的主line：**用状态历史做记忆，用单张图做语义，用离线 VLM 教师训练在线快头，用块长与块内排序去吸收剩余延迟。**

## 2. 严谨定义：延迟分解、可行窗、语义价值

### 2.1 延迟分解

设控制周期为 `Δt`（秒/步，待手册核实，暂按 30 Hz 即 33.3 ms 做参数化），动作块长为 `T_a`（步）。一次交互的延迟分为：

```text
L_obs   = 图像编码 + 上行网络（随声明的图像键数 × 堆叠帧数 × 分辨率增长）
L_act   = 动作下行（T_a × 动作维度，float32；通常远小于图像）
L_infer = 策略前向（产生下一块）
L_head  = 内部快验证头（毫秒级，若已蒸馏）
L_vlm   = 外部/大 VLM 语义验证（百毫秒到秒级，若在环）
L_s     = L_obs + L_infer + L_act          # 产生"下一块"的服务延迟
L_d     = L_obs + L_verify                 # 从块结束到"检测结论可用"的延迟
L_verify= L_head（快路）或 L_vlm（慢路）
```

定义**块内最大陈旧度**：

```text
A_max ≈ L_obs + (T_a − 1)·Δt
```

即块内最后一个动作用到的观测，比"现在"旧了多少。

### 2.2 不可逆窗 B 与可行块长命题

对每个计分步 `g`，定义**不可逆窗** `B_g`：一次干扰发生后，若在 `B_g` 内被检测并重做，仍能保住该步分数；超过 `B_g` 则至少损失一部分。直觉：拉拉链、开合盖、叠毛巾的 B 较大（可逆）；倒液体、插网线、拧药瓶的 B 很小（不可逆或半不可逆）。

**命题 1（延迟-块长可行窗）.** 在"评测端执行完整块后才请求下一块"的保守模型下，若要求（i）不出现计算饥饿、（ii）干扰在不可逆窗内被检测，则必须

```text
T_a ≥ L_s / Δt                       （不饥饿）
T_a ≤ (B_g − L_d) / Δt               （来得及）
⇒ T_a ∈ [ ⌈L_s/Δt⌉ , ⌊(B_g − L_d)/Δt⌋ ]
```

该区间非空的必要条件是

```text
L_s + L_d ≤ B_g          （总延迟预算）
```

若 `L_s ≈ L_d ≈ L`，则退化为 `L ≤ B_g / 2`；若在环 VLM 使 `L_d` 很大，接触密集/不可逆任务会直接**无可行块长**。

*证明*：第一式由"块执行时间 `T_a Δt` 必须覆盖服务时间 `L_s`"直接得到；第二式由"干扰发生在块边界后，最坏要等整块执行完再加检测延迟 `L_d`"得到。两式联立即得。∎

**推论 1（为什么必须把 VLM 移出关键路径）.** 若 `L_vlm > B_g − L_s − L_obs`，则任何 `T_a` 都无法在 B_g 内完成慢路验证；此时要么接受步骤分损失，要么把 VLM 蒸馏成 `L_head` 毫秒级的内部头（UIP-20）。**VLM 的语义能力必须"离线买"，不能"在线租"。**

**推论 2（为什么状态堆叠便宜、图像堆叠昂贵）.** `L_s`、`L_d` 随图像载荷近似线性增长，而状态载荷只有几十个 float。设一帧状态 172 B、一张 480×640 JPEG 约 20–80 KB；状态堆 8 帧 ≈ 1.4 KB，只有一张图的 2%–7%。因此"用状态历史补记忆、用单张图补语义"是延迟约束下的占优策略。

### 2.3 语义验证的价值：L-VoI

在块边界，策略先得到快路结论（几何谓词/内部头），再决定是否调用慢路 VLM。设：

```text
p        = P(当前子目标被撤回 | 观测, 快路)         （可校准）
ΔS       = 若正确检出并重做，预计可保住的步骤分
c_fp     = 假阳性重做的期望成本（时间 + 可信度）
L_cost   = λ·E[L_vlm] + μ·Var[L_vlm]              （延迟与抖动成本）
```

定义**延迟感知的语义信息价值**：

```text
L-VoI = (p·ΔS − (1−p)·c_fp) / (L_cost + ε)
```

决策规则：**仅当 `L-VoI > 0` 且 `L_vlm ≤ B_g − (T_a·Δt + L_obs + L_head)` 时才调用慢路**；否则直接用快路并保守推进。第二个条件保证"即使 VLM 答对了，也已经太晚"的情况不会发生——这正是 v2 没有的约束。

### 2.4 任意时间 VLM（anytime VLM）

VLM 不是固定延迟的黑盒：可以降分辨率、减帧数、换小模型、早退出。设配置 `τ` 的精度为 `A(τ)`、延迟为 `L(τ)`。在线选择

```text
τ* = argmax_τ  E[步骤分 | A(τ), L(τ)]    s.t.  L(τ) ≤ B_g − L_s − L_obs
```

这把"用不用 VLM"升级成"用 VLM 的哪一档"，并允许在不可逆窗紧张时自动降档，而不是一刀切。

### 2.5 观测集的语义率-失真

因为 metadata 固定，观测集设计是一个**握手期鲁棒优化**：

```text
min_{S, r, h}   E[payload(S, r, h)]
s.t.            min_t  Accuracy_t(S, r, h) ≥ 1 − ε     （32 任务最坏情况）
                payload ≤ C_max
```

其中 `S` 是声明的图像键子集，`r` 是分辨率，`h` 是每键堆叠帧数。**状态键可以放心堆叠**（几乎免费），**图像键要按"语义必要性"裁剪**。若评测确实按任务重连，则可把 `S_t, r_t, h_t` 逐任务特化；若不重连，则只能求一个全局鲁棒配置。

### 2.6 进度箭头：时间顺序是免费的监督

对同一子目标内的连续帧，正向时间顺序意味着进度增加，反向意味着进度减少。训练一个**方向判别器** `C(o_i, o_j) → P(j 晚于 i)`；在测试时，若同一子目标内连续帧被判为"倒退"，即 `regressed`。这不需要任何人为干扰标注，只需要成功演示。VLM 教师可进一步给出"倒退了哪个子目标"的语义标签。该信号与 UIP-20 的蒸馏天然互补。

## 3. 瓶颈假设（本轮更新）

- **H1（最高杠杆）**：在远程开环回路里，**语义延迟是步骤分的直接扣分项**。谁能把 `L_d` 压到不可逆窗内，谁就能在 T12/T14/T16/T17/T19/T27 这类"可逆撤回"任务上系统性领先；反之，再强的 VLM 只要慢，就只能在事后解释失败。
- **H2**：`T_a` 不是越大越好，也不是越小越好，而是被 `[L_s/Δt, (B_g−L_d)/Δt]` 夹住；大量接触密集任务的可行窗很窄，必须靠"降 L"而不是"调 k"。
- **H3**：VLM 的正确用法是**离线教师 + 在线快头**；把大 VLM 放进推理关键路径，会同时触发延迟、抖动和单模型合规三重风险。
- **H4**：图像载荷是延迟主项，状态载荷几乎免费；"状态记忆 + 单图语义"比"多帧高清图"更符合本赛制。
- **H5**：延迟的**方差**与均值同等重要，因为超过 B 的损失是凸的；p95 延迟才是应优化的对象，均值会骗人。

## 4. 候选、合并与 v3 清单

围绕两词发散 9 个草案，合并/升级后得到本轮清单（详见产物区）：

- **升级旗舰**：UIP-01′ → **UIP-16 LBSV**（延迟预算内的语义验证；双路验证 + L-VoI 触发 + 可逆性预算）。
- **握手期设计**：UIP-13 ACS → **UIP-17 DACS**（按命题 1 选 T_a）；新增 **UIP-18 RSAC**（块内风险形状：不可逆动作前置、尾部保守）。
- **载荷设计**：UIP-08′ → **UIP-19 SOS**（语义观测集；状态记忆 + 单图语义；率-失真实验）。
- **VLM 的正确位置**：新增 **UIP-20 VTD**（VLM 离线教师蒸馏成在线快头，解决延迟 + 单模型合规）；新增 **UIP-22 TRDS**（时间反演造"撤回"数据，补人扰轴）。
- **延迟隐藏**：UIP-13 的投机思想独立为 **UIP-21 SPIN**（预测下一观测、预生成下一块、只做一致性校验）。
- **保留基础设施**：UIP-11 GSO（离线判分）、UIP-12 DRF（Gazebo 扰动数据）、UIP-14 MSGR（技能图/可逆性先验）、UIP-15 CSG（延迟-抖动安全阀，升级为 deadline-aware）。

## 5. 本轮最大风险（一句话）

**最大的风险是"把离线 VLM 教师的语义能力误当成在线可用的能力"——一旦大 VLM 被放进推理关键路径，延迟与抖动会让接触密集任务的可行块长区间直接为空，而蒸馏/事件触发若没有校准，又会用假阳性重做把省下的步骤分烧回去。**

**→ 本轮最值得押注：UIP-16（LBSV）× UIP-20（VTD）× UIP-17（DACS）组成的"延迟预算内语义验证"闭环——先用离线 VLM 教师把语义判断蒸馏成毫秒级快头，再按不可逆窗选块长，最后用 L-VoI 只在"来得及且值得"时调用慢路。**

## 1. 旗舰深潜：UIP-16 · LBSV（Latency-Budgeted Semantic Verification）

### 1.1 机制（先直觉）

把验证拆成两条路：

- **快路（每块边界都跑）**：状态谓词 + 几何谓词 + 轻量内部头。开销 O(ms)，判断"抓没抓住/放没放到位/进度箭头的方向"。
- **慢路（事件触发）**：VLM 看当前图 + 语言 + 当前计分步，回答"这个子目标是否被撤回/失败类型/可逆性"。只在**快路不确定**且**慢路来得及**且**L-VoI>0** 时调用。

关键不是"VLM 更强"，而是**慢路不能拖垮反应**。快路负责"活着"，慢路负责"看懂"；慢路的结果还要经过 UIP-20 蒸馏，最终在线只剩快头。

### 1.2 与 v2 的差异

| 维度 | v2 UIP-01′ | v3 UIP-16 |
|---|---|---|
| 验证器 | 单一 `V(o,l,g)`，默认即时 | 快路 + 慢路，慢路受 `B_g` deadline 约束 |
| 触发 | 每 k 步/每块 | 快路每块；慢路由 **L-VoI** 与 deadline 双门控 |
| VLM | 可选外部模型 | **离线教师**，在线只用蒸馏头（UIP-20） |
| 延迟 | 作为可信度风险 | 作为**步骤分约束**（命题 1） |
| 动作块 | 假设可返回 ≤k | 明确固定 `T_a`，只能在握手期选（UIP-17） |

### 1.3 状态机

```text
状态 g ∈ {0..K}，每个计分步一个子目标；每块边界观测 o_t。
快路输出 st ∈ {done, ongoing, fail, regressed} 与置信度 conf。
慢路（可选）输出 st_vlm, conf_vlm, B_hat, failure_type。
决策：
  conf < θ                  -> 保持 ongoing，继续当前技能（不重做）
  st = done                 -> g += 1, redo = 0
  st = regressed & 预算允许 -> redo += 1，重做当前子目标
  st = fail & 预算允许      -> redo += 1，重试当前子目标
  否则                      -> 保守推进/交回安全策略
```

`regressed` 的三个触发源：① 状态/几何谓词的时序回退；② 进度箭头 `C(o_{t-1},o_t)` 判为倒退；③ VLM 慢路语义判断。三者取并集，但每条都有独立置信度与成本，避免"一个误判拖着全系统反复重做"。

### 1.4 L-VoI 与慢路门控

```text
p       = 校准后的 P(regressed | o, 快路)
ΔS      = 当前计分步权重 × 可恢复比例
c_fp    = 假阳性重做的期望成本（时间 + 可信度）
L_cost  = λ·E[L_vlm] + μ·Var[L_vlm]
L-VoI   = (p·ΔS − (1−p)·c_fp) / (L_cost + ε)

调用慢路 ⇔ L-VoI > 0
         且 L_vlm^{p95} ≤ B_g − (T_a·Δt + L_obs + L_head)
```

第二个条件是本轮的"新物理"：**答得对但答得晚，等于没答**。

### 1.5 伪代码（严格按官方"每块一次 get_action、返回恰好 T_a 步"）

```python
class LBSVPolicy:                      # UIP-16 + 17 + 18 + 20 + 21 + 15'
    def __init__(self, policy, fast_head, vlm_teacher=None, skill_graph=None,
                 Ta=8, dt=0.033, conf_thr=0.70, max_redo=1,
                 p95_latency_budget_ms=250):
        self.policy = policy
        self.fast = fast_head          # 蒸馏后的内部头，共享骨干
        self.vlm = None                # 在线不加载大 VLM；仅离线教师
        self.sg = skill_graph
        self.Ta = Ta                   # 握手期固定
        self.dt = dt
        self.conf_thr = conf_thr
        self.max_redo = max_redo
        self.budget_ms = p95_latency_budget_ms
        self.reset()

    @property
    def metadata(self):
        # UIP-19: 握手期就选好观测集/分辨率/堆叠与 T_a；运行期不再变
        return {
            "control_space": "joint",
            "obs_delta_indices": {
                "observation.language": [0],
                "observation.images.cam_left_high": [0],
                "observation.images.cam_right_wrist": [0],
                "observation.state.left_arm": [-4, -2, 0],
                "observation.state.right_arm": [-4, -2, 0],
                "observation.state.left_gripper": [-4, -2, 0],
                "observation.state.right_gripper": [-4, -2, 0],
                "observation.state.left_ee_pose_gripper_base": [-4, 0],
                "observation.state.right_ee_pose_gripper_base": [-4, 0],
            },
            "image_resize": {
                "observation.images.cam_left_high": [240, 320],
                "observation.images.cam_right_wrist": [240, 320],
            },
            "action_chunk_size": self.Ta,
            "token": os.environ["UNIBOT_SUBMISSION_TOKEN"],
        }

    def reset(self):
        self.policy.reset()
        self.g = 0
        self.redo = 0
        self.last_obs = None
        self.spec = None               # SPIN 预生成块
        self.t_used_ms = 0.0

    def get_action(self, obs):
        # 1) 快路验证（每块一次；块内无法中断）
        st, conf = self.fast(obs, self.sg.node(self.g))
        B = self.sg.irreversibility_window(self.g)   # 由技能图/离线 VLM 先验给出

        # 2) 慢路：只有在来得及且值得时才调用（在线通常关闭，见 UIP-20）
        if self._slow_path_allowed(st, conf, B):
            st2, conf2, B2 = self._call_vlm_with_deadline(obs, B)
            if conf2 > conf:
                st, conf, B = st2, conf2, B2

        # 3) 状态机 + 预算
        if conf >= self.conf_thr:
            if st == "done":
                self.g += 1; self.redo = 0
            elif st in ("regressed", "fail"):
                if self.redo < self.max_redo and self._budget_ok(B):
                    self.redo += 1
                    self.spec = None          # 作废预生成块

        # 4) 生成下一块：SPIN 命中则直接用，否则重算
        if self.spec is not None and self._consistent(self.spec, obs):
            chunk = self.spec
        else:
            chunk = self._make_risk_shaped_chunk(obs, self.g, self.Ta)
            self.spec = self._speculate(obs, chunk)   # 后台预生成下一块
        self.last_obs = obs
        return chunk                           # dict；各动作键形状必须恰为 (T_a, ...)

    def _slow_path_allowed(self, st, conf, B):
        if self.vlm is None:
            return False                       # 合规默认：在线不调外部 VLM
        p = self.fast.calibrated_p_regressed(st, conf)
        dS = self.sg.step_weight(self.g)
        deadline_ok = (self.vlm.p95_latency_ms / 1000.0
                       <= B - (self.Ta * self.dt + self.obs_latency + self.head_latency))
        return deadline_ok and self._lvoi(p, dS, self.vlm.p95_latency_ms) > 0

    def _budget_ok(self, B):
        # deadline-aware：重做不能把后续步骤挤爆，也不能制造可信度尖峰
        remaining = self.sg.remaining_steps(self.g)
        return (self.t_used_ms + self.budget_ms * (1 + remaining)
                < self.sg.episode_deadline_ms)
```

> 说明：官方 `example_env.step` 只校验形状/令牌，不模拟"块执行耗时"；本地实验必须自己实现"执行 `T_a·Δt` 后再调用"的真实回路，否则会系统性低估延迟的影响。

## 2. UIP-17 · DACS：握手期块长选择（命题 1 的落地）

### 2.1 命题（与想法区 §2.2 一致）

```text
T_a ∈ [ ⌈L_s/Δt⌉ , ⌊(B_g − L_d)/Δt⌋ ]
非空必要条件：L_s + L_d ≤ B_g
```

其中 `L_s = L_obs + L_infer + L_act`，`L_d = L_obs + L_verify`。若 `L_s≈L_d≈L`，则 `L ≤ B_g/2`。

### 2.2 三个直接推论

1. **接触密集/不可逆任务（B_g 小）对慢 VLM 零容忍。** 例如 `B_g=0.4s`、`L_s+L_d=0.5s` 时无可行 `T_a`；只能把 `L_d` 压下来（蒸馏/事件触发/降载荷）。
2. **大块不是免费午餐。** 大 `T_a` 摊销 `L_s`，但把反应滞后推到 `T_a·Δt+L_d`；对可逆任务（B_g 大）可以大块，对不可逆任务必须小块或"块尾去风险"。
3. **延迟方差会吃掉可行性。** 因为损失对 `R` 在 `B_g` 附近是凸的，`p95` 比均值更适合做预算；同一均值下，抖动大的系统可行窗更窄。

### 2.3 可行窗数值表（Δt=33.3ms，参数化推演）

| 总延迟 L（ms） | B=0.4s（不可逆/接触） | B=2.0s（可逆/搬运） |
|---:|---|---|
| 60 | `[2, 10]` ✅ | `[2, 58]` ✅ |
| 120 | `[4, 8]` ✅ | `[4, 56]` ✅ |
| 250 | `[8, 4]` ❌ 空 | `[8, 53]` ✅ |
| 400 | `[13, 0]` ❌ 空 | `[13, 48]` ✅ |

**读法**：`L=250ms` 时，接触密集任务已经没有可行块长；这不是"调 k 能解决"的问题，必须降 `L`（UIP-19/20）。搬运类任务则可以从容用大块。注意：**可行窗为空不等于不能跑**，而是代表"无法保证在 B 内完整恢复"；此时只能选一个使损失最小的块长（下表仿真里的 `k=8` 就是这种"最小伤害"解）。

### 2.4 合成仿真：块长 × 延迟（toy Monte Carlo，不是 benchmark）

模型：`Δt=33ms`、每 episode 60s、干扰率 `μ=1/15s`、每次干扰风险 25 分、块内开环、检测滞后 `R=T_a·Δt+L`、超过 `B` 后按 `(R−B)/B` 线性损失、`T_a·Δt<L` 时按比例计算饥饿。结果（期望步骤分代理）：

| L（ms） | B=0.4s：最优 k（分数） | B=2.0s：最优 k（分数） |
|---:|---|---|
| 60 | k=2/4/8（≈100） | k=2…32（≈100） |
| 120 | k=4/8（≈100） | k=4…32（≈100） |
| 250 | k=8（≈71.5） | k=8…32（≈100） |
| 400 | k=8（≈22.4） | k=16（≈100） |

**观察**：同样的延迟，对 `B` 小的任务是指数级伤害；对 `B` 大的任务几乎无感。这就是"延迟预算"应该按任务/计分步分配的原因。

### 2.5 抖动惩罚（均值 200ms，B=0.4s，合成）

| k | sd=0 | sd=40ms | sd=80ms | sd=120ms |
|---:|---:|---:|---:|---:|
| 2 | 0.00 | 0.00 | 0.39 | 2.03 |
| 4 | 0.00 | 0.19 | 2.23 | 5.29 |
| 8 | 16.00 | 16.25 | 18.33 | 21.79 |

**读法**：当 `R` 接近 `B` 时，方差本身就是分数损失。优化目标应是 `p95` 延迟与抖动，而不是均值；这直接支撑 UIP-21（投机）与 UIP-15′（安全阀）。

## 3. UIP-18 · RSAC：风险形状动作块

### 3.1 问题

`T_a` 固定且块内不可中断，所以"块内动作的顺序/风险"本身是设计变量。一次干扰可能发生在块内任意位置；越靠后的动作，所依据的观测越旧。

### 3.2 定义

对动作 `a` 定义：

```text
ι(a) ∈ [0,1]   不可逆性：在错误状态下执行会损失多少步骤分
σ(a) ∈ [0,1]   信息依赖性：多依赖最新观测
A_j = L_obs + j·Δt   块内第 j 步的观测陈旧度
h(A) = 干扰在陈旧度 A 内发生的风险（可由数据/仿真估计）
```

目标是安排技能内的动作/相位，使

```text
minimize   Σ_j  ι(a_j) · h(A_j)
subject to 动作序列满足技能前置条件
```

因为 `h` 随 `A` 单调增，**高不可逆、高信息依赖的动作应尽量前置；块尾应放低不可逆的保守动作**。

### 3.3 两个可操作机制

1. **相位对齐（phase-aligned chunking）**：让块边界落在"下一次不可逆接触之前"而不是中途。若当前块提前完成，用安全尾（悬停/慢速/回撤）填充到 `T_a`，使下一次 `get_action` 恰好发生在信息最关键的时点。这是把"固定块长"变成"可设计的边界"。
2. **块尾去风险（safe tail）**：最后 `m` 步只做低不可逆动作（保持/回撤/慢速接近），保证即使块内发生撤回，损失也被 `m` 截断。对 `B_g` 小的任务，`m` 应更大；对搬运类任务，`m` 可以接近 0。

### 3.4 伪代码

```python
def make_risk_shaped_chunk(policy, obs, g, Ta):
    plan = policy.plan(obs, g)              # 技能图给出动作/相位序列
    # 1) 找到下一个不可逆动作的索引
    j_star = first_index(plan, lambda a: irreversibility(a) > 0.5)
    # 2) 尽量让块边界对齐到 j_star 之前；不足/超出用安全尾补齐
    if j_star is not None:
        plan = align_boundary(plan, j_star, Ta)
    # 3) 块尾 m 步替换为低不可逆动作
    m = tail_len(irreversibility_window(g), Ta)
    plan[-m:] = safe_hold_actions(obs, m)
    assert len(plan) == Ta
    return pack(plan)                        # 形状 (Ta, ...)
```

## 4. UIP-19 · SOS：语义观测集（握手期最小充分载荷）

### 4.1 原则

> **状态做记忆，单图做语义；图像按任务必要性裁剪，状态可放心堆叠。**

- 状态：`left/right_arm[7]`、`left/right_gripper[1]`、左右 ee pose `[6]`、`lower_body[15]` 共 43 个 float ≈ **172 B/帧**；堆 8 帧 ≈ **1.4 KB**，可忽略。
- 图像：480×640×3，JPEG q95/4:4:4，单张约 **20–80 KB**（实际随场景复杂度变化，必须测）；4 路 × 1 帧 ≈ **80–320 KB**；4 路 × 2 帧 ≈ **160–640 KB**。

### 4.2 载荷-延迟估算（参数化，需实测）

假设 4 路图、每张 80 KB、状态堆 8 帧：

| 配置 | 载荷 | 10 Mbps 上行 | 100 Mbps 上行 |
|---|---:|---:|---:|
| 4 图 × 1 帧 | ≈321 KiB | ≈263 ms | ≈26 ms |
| 2 图 × 1 帧（40 KB/图） | ≈81 KiB | ≈66 ms | ≈6.6 ms |
| 1 图 × 1 帧（40 KB） | ≈41 KiB | ≈33 ms | ≈3.3 ms |
| 仅状态 × 8 帧 | ≈1.4 KiB | ≈0.1 ms | ≈0.01 ms |

**读法**：在上行带宽未知的情况下，**图像键数和堆叠帧数是最大的延迟杠杆**；把"多帧图"换成"状态历史 + 单帧图"通常能把 `L_obs` 降一个数量级。

### 4.3 最小充分观测集的离线实验

对每个任务 `t`，枚举候选 `(S, r, h)`：

```text
S ⊆ {head_left, head_right, wrist_left, wrist_right}
r ∈ {480×640, 320×240, 240×320, 160×120}
h ∈ {1, 2, 3}
```

用离线 VLM 教师 + 人工抽检，测"进度/回归判断"的 AUROC 与校准误差；求：

```text
最小载荷配置 s.t. 最坏任务 AUROC ≥ 1−ε
```

若评测确认按任务重连，则逐任务取最优；否则取最坏情况最优的全局配置。**这是本轮最便宜、最确定能落地的收益之一。**

## 5. UIP-20 · VTD：把 VLM 变成离线教师

### 5.1 为什么必须离线

- **延迟**：大 VLM 的 `L_vlm` 很容易超过接触密集任务的 `B_g`，在线调用直接让可行窗为空。
- **抖动**：VLM 的排队/批处理延迟方差大，会同时伤步骤分和可信度。
- **合规**：推理期加载第二个大模型/调用外部 API，可能被判"非单模型"。
- **成本**：N 端口并发时，在线 VLM 的显存/吞吐不可控。

### 5.2 蒸馏目标

教师（离线、可本地部署的开源 VLM，提交前须做许可/版本/污染审计）在以下数据上打标签：

1. 32 个公开数据集的帧（成功演示）；
2. UIP-12 DRF 的 Gazebo 扰动-恢复 rollout；
3. UIP-22 TRDS 的时间反演"撤回"片段；
4. 合成退化（遮挡、模糊、光照、运动模糊）以匹配真机。

学生头与策略共享视觉-语言骨干，输出多任务：

```text
head_progress   : 子目标状态 ∈ {done, ongoing, regressed, fail}
head_direction  : 进度箭头（正向/倒退）
head_reversible : B 的离散档（小/中/大）或回归值
head_failure    : 失败类型（滑落/错物/遮挡/卡住/被拿走）
```

损失：

```text
L = L_ce(progress) + L_bce(direction) + L_huber(B_hat)
  + L_ce(failure) + λ_cal·L_calibration(ECE/Brier)
```

用温度缩放 / conformal prediction 做校准，使 `conf` 可用于门控。最终**只导出学生 checkpoint**；教师只存在于训练/标注阶段。

### 5.3 与 v2 的关系

- 替换 v2 "外部 VLM 验证器"的合规风险；
- 给 UIP-16 提供 `conf` 与 `B_hat`；
- 给 UIP-14 技能图提供"可逆性/失败类型"节点属性；
- 给 UIP-15′ 提供假阳性成本估计。

### 5.4 验收指标

| 指标 | 目标 |
|---|---|
| 学生 vs 教师 AUROC | 差距 ≤ 3–5 个点（按任务分层） |
| p95 在线延迟 | ≤ 5 ms（单头，共享骨干） |
| 校准 ECE | ≤ 0.05 |
| 单模型审计 | 推理期只加载一个 checkpoint，无外部 API 调用 |
| 假阳性率 @ 90% recall | 尽可能低；用 conformal 阈值控制 |

## 6. UIP-22 · TRDS：时间反演造"撤回"

### 6.1 直觉

成功演示正向播放是"完成任务"；**倒放**就是"把已完成进度撤回"——开盖变关盖、拉拉链变拉开、叠好变翻开。虽然倒放帧在物理上不完全真实（重力/摩擦不可逆），但它提供了**视觉上正确的"倒退"负样本**，而且零采集成本。

### 6.2 构造

给定成功 episode 的帧 `o_0..o_N` 与动作 `a_0..a_N`：

1. 选子目标边界 `k` 与回退长度 `m`；
2. 合成观测序列：`o_0..o_k`（正向）→ `o_{k-1},...,o_{k-m}`（倒放，"人为撤回"）；
3. 恢复段：从 `o_{k-m}` 起接回原始正向演示（动作 `a_{k-m}..a_N`）；
4. 用离线 VLM 教师过滤视觉不连续/物理荒谬的片段。

这样就得到 **(正常进度 → 撤回 → 恢复)** 的观测-动作三元组。倒放段只用于训练验证器/恢复策略的"检测与重做"，不用于学习倒放动作本身。

### 6.3 边界

- **倒放不是物理仿真**：不要用它训练低层动力学；低层动作仍以 Gazebo/真机为准。
- **视觉伪影**：用 VLM 教师 + 人工抽检过滤。
- **与 UIP-12 互补**：DRF 提供物理上更可信的干扰，TRDS 提供几乎零成本的规模覆盖；两者混合训练。

## 7. UIP-21 · SPIN：投机流水线 + UIP-15′ 安全阀

### 7.1 投机流水线

评测端执行当前块 `A_t` 的 `T_a·Δt` 期间，服务端是空闲的（除了等待）。把这段时间用来：

1. 用轻量前向模型/意图动作预测下一观测 `ô_{t+1}`；
2. 预生成 `A_{t+1}^{spec}` 与一个"恢复候选" `A_{t+1}^{rec}`；
3. 真实 `o_{t+1}` 到达时，用快路算一致性分数 `κ`；
4. `κ > θ` 且快路无 `regressed` → 直接返回 `A_{t+1}^{spec}`；否则重算/用恢复块。

```text
命中率 h = P(κ > θ)
E[L] ≈ h·L_check + (1−h)·(L_check + L_full)
Var[L] 随 h 上升而下降
```

**收益**：压低平均延迟与抖动，缓解命题 1 的 `L_s` 约束。**风险**：预测错误时返回陈旧动作；用保守一致性阈值 + 恢复候选兜底。

### 7.2 UIP-15′：deadline-aware 安全阀

- 所有重做必须满足"剩余 episode 预算 > 本次重做成本"；
- 用 `p95` 延迟而非均值做预算；
- 限制单位时间内的慢路调用次数，避免可信度曲线出现尖峰；
- 动作平滑/限幅，避免统计异常；
- 假阳性预算：当 `c_fp` 估计升高时自动提高 `conf_thr`，宁可少重做。

## 10. 合规与风险

- **单模型**：在线只加载一个 checkpoint；VLM 只做离线教师；不做推理期集成/路由/外部 API。
- **接口红线**：`T_a` 形状必须恰好 `(T_a, …)`；`obs_delta_indices`/`image_resize` 必须在握手期确定；`meta.token` 每步携带。
- **可信度**：慢路调用会造成延迟尖峰；用 UIP-15′ 分摊/限频，保持 `p95` 稳定。
- **仿真/数据**：TRDS 倒放不是物理真值；GSO 是结构裁判不是成败裁判；必须留真机锚点。
- **统计**：小样本榜单差异不可当真；先算样本量，再谈提升。
- **手册缺口**：实际控制频率 `Δt`、episode 时限、评测轮次、5 轴中的位置/干扰物/背景仍未从飞书手册核实；本轮的 `B_g`、`μ`、`Δt` 都是**参数化变量**，不是定值。

## 12. 本轮最大风险 & 押注

**一句话**：最大的风险是把"离线 VLM 教师的语义能力"误当成"在线可用的能力"——一旦慢 VLM 进入关键路径，延迟/抖动会让接触密集任务的可行块长区间直接为空；而蒸馏/事件触发若校准不好，假阳性重做又会把省下的步骤分烧回去。

**→ 押注：UIP-16（LBSV）× UIP-20（VTD）× UIP-17（DACS）的"延迟预算内语义验证"闭环**——用离线 VLM 教师换毫秒级在线快头，用不可逆窗选块长，用 L-VoI 只在"来得及且值得"时调用慢路。它同时回答了两个灵感词：**通信延迟**要求我们把块长、载荷、块内风险当成约束；**视觉语言模型**要求我们把它的语义能力放在离线教师的位置，而不是推理关键路径上。
