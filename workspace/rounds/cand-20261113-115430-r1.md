# 第 1 轮（承接第 66 轮「RAS 情绪驱动闭环」IP-224~233；灵感循环第 1 轮；本轮灵感：「交互设计」×「机器人操作系统」）

> 第 66 轮 RAS 把 VISTA 的「被动故障响应闭环」升级为「主动意图感知闭环」，回答了「谁该控制、何时控制、控制多少」。但 RAS 的闭环仍然完全发生在**机器人内部**：它感知情绪、归因故障、缩放风险，却从未把「用户如何理解、如何表达、如何撤销」当作一等约束。交互设计恰恰指出：真正的失败往往不是控制误差，而是**执行鸿沟（gulf of execution）**与**评估鸿沟（gulf of evaluation）**——用户想做的系统不给做，系统做了用户看不懂。机器人操作系统（ROS）则提供了节点图、QoS 与 executor 调度，却唯独没有为「人」这个最关键的节点声明 QoS。
>
> 本轮命题：
>
> **把交互设计的三条公理——可发现性（discoverability）、状态一致性（consistency）、可逆性（reversibility）——编译成 ROS 原生的、可调度、可认证、可降级的「交互契约（Interaction Contract）」，让交互质量成为与实时控制 deadline 同等级的 OS 级资源。**
>
> 命名 **IC-ROS：Interaction-Contract Robot Operating System（交互契约机器人操作系统）**。它不问「谁控制」，而问「**控制意图如何被用户表达、理解和反悔**」。三层栈由此闭合：`VISTA（故障层）→ RAS（意图层）→ IC-ROS（交互层）`。

## 0. 直觉与动机

**灵感 1（交互设计 → 鸿沟是资源赤字，不是界面缺陷）**
直觉：Norman 的两大鸿沟常被当成 UI 问题，但从系统角度看，它们都能还原为**资源赤字**：
- 执行鸿沟 = **可发现性资源不足**：当前可选动作集 `A` 没有覆盖用户意图 `I`；
- 评估鸿沟 = **一致性资源不足**：显示状态 `s_disp` 与用户心智模型 `s_mind` 之间存在版本偏斜（version skew）；
- 可逆性 = **时间资源不足**：撤销窗口 `W_rev` 短于用户发现并纠正错误的反应时。

一旦这样还原，交互设计就变成了一个**可调度性（schedulability）问题**：资源够不够、deadline 满不满足、降级是否安全。这是把 UX 从「审美判断」拉进「工程可证」的关键一步。

**灵感 2（机器人操作系统 → 把「人」声明成一个 QoS 节点）**
直觉：ROS 2 里每个传感器、控制器、规划器都能声明 QoS（reliability、durability、deadline、liveliness）。**唯独人不声明**。于是系统会对一个摄像头掉帧报警，却对「用户盯着屏幕 1.2 秒没收到反馈」无动于衷。IC-ROS 的第一个动作，就是给人类节点 `H` 补上 QoS：感知时延 `τ_perc`、动作时延 `τ_act`、认知预算 `B_cog`、技能水平 `κ_skill`。人一旦成为图里的节点，交互质量就能像 topic 一样被监控、被调度、被降级。

**灵感 3（契约即编译目标）**
直觉：现代交互设计常用 design token / spec 描述「这个按钮在什么状态下可点、反馈多快、能否撤销」。IC-ROS 把这份 spec **编译**成 ROS 2 的节点图、topic 类型、QoS profile 与 executor 配置——就像编译器把高级语言编译成 ISA。编译产物中，每条交互契约 `C_i` 都是一个可被 `ros2 doctor` 诊断、可被 admission control 拒绝的运行时对象。

**灵感 4（渐进式披露 → 单调安全的降级）**
直觉：RAS 在算力不足时降级控制；IC-ROS 在**交互资源不足**时降级「可提供的动作集」。关键约束是**单调性**：降级只能**移除** affordance，绝不新增——这样交互降级永远不会把系统带进一个更危险的可达状态集。这把「渐进式披露（progressive disclosure）」从一个 UX 技巧升级为一条**安全不变式**。

**灵感 5（跨轮合流 → IC-ROS 骑在 RAS/VISTA 之上）**
- VISTA 回答「哪一层坏了」；
- RAS 回答「谁控制、控制多少」；
- IC-ROS 回答「**这个控制意图如何被表达、被理解、被反悔**」。

当交互契约不可满足时，IC-ROS 不是悄悄丢反馈，而是**回压（backpressure）**给 RAS：请求缩短认证前缀 `k*RAS`、降低 `λ_risk` 或切换到更保守的情绪探针模式。交互层由此获得对控制层的**反向否决权**。

## 1. 形式化定义（增量：定义 245–260）

- **定义 245（IC-ROS 总览）**：`IC-ROS = (ICC, HQN, iQoS, IAC, GM, PDD, REV, LSS, J_IC)`，即「契约编译器、人类 QoS 节点、交互 QoS 运行时、交互准入控制、鸿沟监控器、渐进披露降级器、可逆服务、可读性信号调度器、交互证书」。定位：VISTA/RAS 之上的**交互层**。不变式：契约编译、鸿沟推理、证书构建只在语义流；实时流只做 deadline 检查、staleness 比较、撤销令牌 TTL 校验，**零学习写操作**。
- **定义 246（交互契约 Interaction Contract）**：`C = (A, I_dom, D_fb, S_cons, W_rev, B_cog, R_fail)`，其中 `A` 为当前可提供的 affordance 有限集，`I_dom` 为意图域，`D_fb` 为反馈截止期，`S_cons` 为不得同时成立/同时显示的状态对集合，`W_rev` 为可逆窗口，`B_cog` 为认知负载预算，`R_fail` 为失败/降级语义（fail-safe 方向）。
- **定义 247（人类 QoS 节点 Human Node）**：`H = (τ_perc, τ_act, κ_skill, σ_cog(t))`。动作时延用 Fitts 律近似 `τ_act = a + b·log2(2D/W)`，选择时延用 Hick 律近似 `τ_choice = c + d·log2(n+1)`；`σ_cog(t)` 为随任务负荷变化的认知状态。
- **定义 248（交互 QoS iQoS）**：在 ROS 2 QoS 之上扩展 `iQoS = (reliability, durability, deadline, lifespan, D_fb, staleness_max, legibility_min, undo_ttl)`。其中 `staleness_max` 是显示状态允许的最大陈旧度，`legibility_min` 是动作可理解度下界（借鉴 Dragan 的可读性运动）。
- **定义 249（执行鸿沟度量 G_exec）**：`G_exec(t) = min_{a∈A_t} c(I_t, a)`，`c` 为意图-动作匹配代价；若 `A_t` 无匹配项则 `G_exec = ∞`。可发现性要求即 `G_exec ≤ ε_exec`。
- **定义 250（评估鸿沟度量 G_eval）**：设用户信念估计 `b_t`、显示状态 `s_disp,t`，则 `G_eval(t) = D_KL(b_t || s_disp,t) + γ_s·staleness_t`。`staleness_t` 为 `s_disp,t` 距真实状态的时延；`γ_s` 为陈旧惩罚系数。
- **定义 251（契约可调度性 Contract Schedulability）**：契约集 `{C_i}` 在资源 `R=(U0,U1,B_cog)` 下可调度，当且仅当（a）抢占式 EDF 总利用率 `Σ C_i/D_i ≤ 1`（非抢占控制任务另加阻塞项 `B_max/D_min ≤ 1`）；（b）认知预算 `Σ B_i/D_i ≤ B_cog`；（c）可逆窗口 `W_rev,i ≥ τ_perc + τ_act + τ_notice,i`。
- **定义 252（交互准入控制 IAC）**：`admit(C) ⇔ sched(C) ∧ cog(C) ∧ rev(C)`。不可准入时返回 `RENEGOTIATE`，而非静默超时。
- **定义 253（渐进披露与单调降级）**：affordance 集上定义偏序 `A' ≼ A`（`A' ⊆ A`）。降级算子 `↓_d(A)` 满足不变式 `↓_d(A) ⊆ A` 且只移除低优先级 affordance；任何时刻不允许通过降级新增 affordance。
- **定义 254（可逆令牌 Reversibility Token）**：`u = (action_id, snapshot_hash, t_create, ttl, owner)`。`u` 有效当且仅当 `now - t_create ≤ min(ttl, W_rev)` 且 `snapshot_hash` 链完整；破坏性动作必须携带有效令牌才可提交。
- **定义 255（可读性信号约束）**：对机器人动作序列 `π`，存在信号消息 `m`（轨迹塑形、注视、语音、灯光）满足 `ℓ(m) ≥ legibility_min` 且 `D_signal(m) ≤ D_fb`，其中 `ℓ` 为可读性评分。
- **定义 256（交互证书 J_IC）**：`J_IC = (J_RAS, contract_id, Ĝ_exec, Ĝ_eval, iQoS_hash, rev_token_ttl, pd_level, ic_ros_ver)`。`Valid(J_IC) ⇔ Valid(J_RAS) ∧ Ĝ_exec ≤ ε_exec ∧ Ĝ_eval ≤ ε_eval ∧ (破坏性动作 ⇒ 令牌有效) ∧ pd_level ≥ 0`。
- **定义 257（一致性集与模式错误）**：`S_cons` 中每对 `(s_i, s_j)` 表示两状态不得同时激活或同时显示。模式错误指示 `mode_error_t = 1[∃(s_i,s_j)∈S_cons: s_i∈s_disp,t ∧ s_j∈s_disp,t]`。
- **定义 258（交互故障假设 H_int）**：在 RAS 假设集之上新增 `H_int = {AMB 歧义, LAG 反馈滞后, INC 状态不一致, IRREV 不可逆破坏, OVL 认知过载}`，构成 `ℋ_IC = ℋ_RAS × H_int`。联合后验中 `P(H_int | monitor)` 由 GM 的事件驱动。
- **定义 259（契约重协商 Renegotiation）**：`C* = argmax_{C'≼C, feasible(C')} U(C')`，`U` 为用户效用；只允许沿 `≼` 下降方向重协商，保证不引入新风险。
- **定义 260（双层 iQoS Executor）**：`EX = (L0, L1)`。`L0` 为 VISTA/RAS 硬实时控制任务，`L1` 为人类感知 deadline 任务。调度键为 `(deadline, level)`：EDF 主序，`level` 仅用于同 deadline 平局。`L0` 不得被 `L1` 饿死，预留 `U0 ≤ 1 - U1`。

## 2. 关键算法骨架

```python
# IP-234 交互契约编译器：把交互 spec 编译为 ROS 2 图 + QoS + executor 配置
class InteractionContractCompiler:
    def compile(self, spec):
        contracts = []
        for s in spec['interactions']:
            A = build_affordances(s['actions'])
            C = InteractionContract(
                A=A, I_dom=s['intent_domain'],
                D_fb=s['feedback_deadline_ms'],
                S_cons=set(map(frozenset, s['inconsistent_pairs'])),
                W_rev=s['reversibility_window_ms'],
                B_cog=s['cognitive_budget_bits'],
                R_fail=s['degradation_direction'])
            assert self._monotone_order_ok(C)
            contracts.append(C)
        graph = emit_ros2_graph(contracts)          # nodes / topics / services
        qos = {c: emit_iqos(c) for c in contracts}  # deadline / lifespan / undo_ttl
        return contracts, graph, qos

    def _monotone_order_ok(self, C):
        return all(phi <= C.B_cog for phi in C.A.priorities)


# IP-237 双层 iQoS Executor
class IQoSExecutor:
    def __init__(self, U0_reserved):
        self.U0 = U0_reserved

    def step(self, ready):
        # 人类感知任务先做准入，控制任务始终保留 U0
        human = [t for t in ready if t.level == 1]
        admit = self._admission(human)
        tasks = [t for t in human if t in admit] + \
                [t for t in ready if t.level == 0]
        tasks.sort(key=lambda t: (t.deadline, t.level))
        if total_util(tasks) + self.U0 > 1.0:
            degrade_level = select_pd_level(tasks)   # 单调降级
            return 'DEGRADE', degrade_level
        return 'RUN', tasks[0]


# IP-239 鸿沟监控器
class GulfMonitor:
    def update(self, intent, A, b, s_disp, staleness, S_cons):
        G_exec = min((cost(intent, a) for a in A), default=float('inf'))
        G_eval = kl_div(b, s_disp) + GAMMA_S * staleness
        mode_error = any(si in s_disp and sj in s_disp
                         for si, sj in S_cons)
        events = []
        if G_exec > EPS_EXEC: events.append('H_int:AMB')
        if G_eval > EPS_EVAL: events.append('H_int:INC')
        if staleness > STALENESS_MAX: events.append('H_int:LAG')
        if mode_error: events.append('H_int:INC')
        return {'G_exec': G_exec, 'G_eval': G_eval,
                'mode_error': mode_error, 'events': events}


# IP-240 渐进披露降级器（单调、只减不增）
class ProgressiveDisclosure:
    def degrade(self, C, level):
        removed = set()
        for a in sorted(C.A, key=lambda x: x.priority):
            if len(removed) >= level:
                break
            if a.is_reversible or a.priority > 0:
                removed.add(a)
        C.A = C.A - removed          # 不变式：只做集合差
        assert C.A <= C.A_prev
        return C, removed


# IP-241 可逆服务
class ReversibilityService:
    def issue(self, action):
        snap = snapshot(action.pre_state)
        ttl = min(action.W_rev, DEFAULT_UNDO_TTL)
        return Token(action.id, hash(snap), now(), ttl, owner=action.owner)

    def undo(self, token, state):
        if now() - token.t_create > token.ttl:
            return False, 'EXPIRED'
        if hash(state) != token.snapshot_hash:
            return False, 'HASH_MISMATCH'
        restore(token.snapshot_hash)
        return True, 'OK'


# IP-242 可读性信号调度器
def schedule_legibility(action_seq, D_fb, legibility_min):
    m = choose_signal(action_seq)          # 轨迹塑形 / 注视 / 语音
    if legibility(m) < legibility_min:
        m = escalate_signal(m)             # 升级到更显式通道
    return m if deadline(m) <= D_fb else 'REJECT'


# IP-234~243 端到端：IC-ROS 一层，骑在 RAS 之上
def IC_ROS_round(M, obs, spec):
    # 1) 先跑 RAS 得到控制意图与风险
    k_ras, lambda_risk, joint_post, face_gate = RAS_round(M, obs)
    tau_intent = M.vista.pi_sigma.prefix_dispatch(M.A[:k_ras])

    # 2) 编译/加载交互契约，并做人机时序对齐
    contracts = M.icc.load(spec)
    C = contracts[M.current_task]
    H = M.hqn.estimate(obs)                     # τ_perc, τ_act, σ_cog

    # 3) 反馈 deadline 与可读性
    sig = schedule_legibility(tau_intent, C.D_fb, C.legibility_min)

    # 4) 鸿沟监控
    gulf = M.gm.update(intent=M.intent_est, A=C.A,
                       b=M.belief_est, s_disp=M.display_state,
                       staleness=M.staleness, S_cons=C.S_cons)

    # 5) 准入 + 单调降级（关键：不可行时回压 RAS，而非静默丢反馈）
    ok, payload = M.executor.step(M.ready_tasks())
    if ok == 'DEGRADE':
        C, removed = M.pdd.degrade(C, payload)
        # 反向否决：交互层要求 RAS 更保守
        k_ras = min(k_ras, M.ras.max_prefix_for(C))
        lambda_risk = max(lambda_risk, M.ras.min_lambda_for(C))
        tau_intent = M.vista.pi_sigma.prefix_dispatch(M.A[:k_ras])

    # 6) 破坏性动作必须可逆
    if is_destructive(tau_intent):
        token = M.rev.issue(tau_intent)
        assert token is not None
    else:
        token = None

    # 7) 构建交互证书
    J_ic = build_certificate(M.J_ras, C, gulf, token)
    assert valid(J_ic)

    return tau_intent, sig, C, gulf, J_ic
```

## 3. 推导

**引理 11（评估鸿沟的可界定上界）** 若在窗口 `[t-T, t]` 内每次反馈均满足 `D_fb`、显示陈旧度 `staleness ≤ staleness_max`、且无模式错误，则 `G_eval(t) ≤ γ_s·staleness_max + κ·exp(-λ·D_fb)`。`κ,λ` 由人类信念更新速率决定。直觉：反馈越及时、越新，用户信念越贴近显示状态；模式错误是唯一会把误差放大的项，故被单独排除。

**引理 12（单调降级保持安全）** 若可达危险状态集 `Reach(·)` 关于 affordance 集单调（`A' ⊆ A ⇒ Reach(A') ⊆ Reach(A)`），则对任意降级级别 `d`，安全不变式 `Reach(↓_d(A)) ⊆ Reach(A)` 成立。证明：`↓_d` 只做集合差，任何在 `A'` 下可达的状态必然在 `A` 下可达；故降级不可能引入新的危险状态。这是渐进式披露能作为「安全降级」而非「风险重分配」的根本原因。

**定理 11（契约可调度 ⇒ 交互失败概率有界）** 设契约集在 `R` 下 EDF 可调度，单项原子违约概率为 `p_i` 且相互独立。则在时域 `T` 内交互失败（任一 `G_exec`、`G_eval`、模式错误、不可逆事件）的概率满足 `P_fail(T) ≤ 1 - ∏_i (1 - p_i)^{T/D_i} ≤ Σ_i (T/D_i)·p_i`。若进一步 `p_i = 0`，则 `P_fail(T) = 0` 当且仅当无模式错误。推论：交互质量可以像实时系统一样，用可调度性 + 原子违约率来**预先认证**，而不是事后可用性测试。

**定理 12（双层可行性条件）** 若控制层为非抢占、人类层可抢占，则双层 iQoS Executor 可行的一个充分条件是 `U0 + U1 + B_max/D_min ≤ 1`，其中 `B_max` 为最长非抢占控制段、`D_min` 为全局最短 deadline。证明：对控制层引入阻塞项后，剩余处理器带宽按 EDF 分配给人类层；总利用率条件保证无任务错过 deadline。这说明「交互层」与「控制层」的共存有明确的可调度边界，不是靠调参碰运气。

**定理 13（可逆性降低不可逆代价）** 设用户在 `W_rev` 内发现并纠正错误的概率为 `q(W_rev)`，撤销代价为 `c_u`，不可逆错误代价为 `c_irr`。则期望代价 `E = (1-q)c_irr + q·c_u`。最优窗口 `W_rev* = Q^{-1}(1 - c_u/c_irr)`，即用户纠正时延分布的对应分位数。推论：`W_rev` 不应拍脑袋设为固定 5 秒，而应由任务风险比 `c_u/c_irr` 决定。

## 6. 本轮最大风险

**一句话**：IC-ROS 的全部可调度性与安全保证都建立在「人类的感知/动作/认知参数是可测量、平稳、可跨人群聚合的常量」这一假设上；而真实用户的认知状态高度非平稳、异质且依赖语境，于是一个**数值上满足契约**的系统，可能系统性地剥夺了用户当下最需要的可发现性与控制感——**形式化本身制造了虚假的安全感**。

**次级风险与缓解**：
1. **参数漂移**：`τ_perc/τ_act/B_cog` 随疲劳、任务负荷漂移 → 在线贝叶斯更新 + 契约视界缩短；
2. **度量不可观测**：`b_t`（用户信念）无法直接测 → 用交互探针/眼动/中断率做代理，并给出置信区间；
3. **降级引发挫败**：单调降级可能移除用户正需要的动作 → 降级前先给「可发现性替代路径」并记录申诉；
4. **合约爆炸**：交互组合导致契约数量指数增长 → 用契约模板 + 参数化复用；
5. **与 RAS 的回压振荡**：交互层与意图层互相收紧可能震荡 → 对回压加一阶低通/滞回（hysteresis）。

```python
def iqos_step(ready, U0_reserved):
    human = [t for t in ready if t.level == 1]
    admitted = [t for t in human if admit(t)]
    tasks = admitted + [t for t in ready if t.level == 0]
    tasks.sort(key=lambda t: (t.deadline, t.level))
    if total_util(tasks) + U0_reserved + blocking(tasks) > 1.0:
        return 'DEGRADE', select_pd_level(tasks, blocked=admitted)
    return 'RUN', tasks[0]


# IP-239 鸿沟监控
def update_gulf(intent, A, belief, disp, staleness, S_cons):
    g_exec = min((cost(intent, a) for a in A), default=float('inf'))
    g_eval = kl_div(belief, disp) + GAMMA_S * staleness
    mode_error = any(si in disp and sj in disp for si, sj in S_cons)
    events = []
    if g_exec > EPS_EXEC:  events.append('AMB')
    if g_eval > EPS_EVAL:  events.append('INC')
    if staleness > STALENESS_MAX: events.append('LAG')
    return dict(G_exec=g_exec, G_eval=g_eval,
                mode_error=mode_error, events=events)


# IP-240 单调降级
def degrade(C, level):
    removed, kept = set(), set(C.A)
    for a in sorted(C.A, key=lambda x: x.priority):
        if len(removed) >= level:
            break
        removed.add(a); kept.discard(a)
    C.A = kept
    assert C.A <= C.A_prev          # 只减不增
    return C, removed


# IP-241 可逆服务
def issue_token(action):
    snap = snapshot(action.pre_state)
    return Token(action.id, hash(snap), now(),
                 min(action.W_rev, DEFAULT_UNDO_TTL), action.owner)

def undo(token, state):
    if now() - token.t_create > token.ttl:
        return False, 'EXPIRED'
    if hash(state) != token.snapshot_hash:
        return False, 'HASH_MISMATCH'
    restore(token.snapshot_hash)
    return True, 'OK'

    if legibility(m) < legibility_min:
        m = escalate_signal(m)
    return m if deadline(m) <= D_fb else 'REJECT'
```

## 4. 推导

**引理 11（评估鸿沟界）** 若窗口内反馈均满足 `D_fb`、`staleness ≤ staleness_max`、无模式错误，则
```
G_eval(t) ≤ γ_s·staleness_max + κ·exp(-λ·D_fb)
```

**引理 12（单调降级保持安全）** 若 `A' ⊆ A ⇒ Reach(A') ⊆ Reach(A)`，则 `Reach(↓_d(A)) ⊆ Reach(A)`。

**定理 11（可调度 ⇒ 交互失败率有界）** 若 EDF 可调度、原子违约概率 `p_i` 独立，则
```
P_fail(T) ≤ Σ_i (T/D_i)·p_i
```
且 `p_i = 0` 时，无模式错误即 `P_fail = 0`。

**定理 12（双层可行性）** 控制层非抢占、人类层可抢占时，充分条件为
```
U0 + U1 + B_max/D_min ≤ 1
```

**定理 13（可逆窗口最优）** 期望不可逆代价
```
E(W_rev) = (1-q)c_irr + q·c_u,   W_rev* = Q^{-1}(1 - c_u/c_irr)
```
即撤销窗口应由风险比 `c_u/c_irr` 决定，而非固定常量。
