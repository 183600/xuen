# 第 1 轮 · 思维起锚：TPD-MPD —— 任务规划-动态避障-多端口部署协同

## 直觉锚点与动机链条

- 传统流水线中任务规划、动态避障、多端口部署常被割裂设计：规划追求全局最优但假设环境静态；避障保证局部安全但可能破坏任务时序；部署追求负载均衡但忽视避障引入的时延抖动。三者脱耦导致规划-执行错配、避障引发任务死锁、端口负载振荡。
- 灵感词映射：
  - 任务规划 → 层次时序约束网络生成可调度任务图，并在任务节点上显式携带时间窗口与资源需求。
  - 动态避障 → 速度障碍 VO 在线形变约束集，将障碍预测位置转化为任务时间轴上的硬/软延时。
  - 多端口部署 → 端口能力-延迟-占用三元成本的稳定匹配，把避障产生的延时裕量作为分配惩罚项。
- 关键设计洞察：把避障产生的时延裕量 Δ 作为规划层软约束，把端口实时占用作为规划层资源约束，形成闭环：规划产生时间窗口 → 避障修正窗口 → 部署锁定窗口 → 执行反馈回规划。

## 形式化定义

### 基本符号
- 任务集 T = {t_i}, i∈[n]。每个 t_i 有持续时间 d_i、资源需求 r_i、 deadline_i、前置集 pred(i)。
- 端口集 P = {p_k}, k∈[m]。端口能力 c_k、通信延迟 l_k、当前占用区间 O_k = {[s_j, e_j]}。
- 动态障碍 o_j(t) ∈ ℝ^3, 速度上界 v_o。
- 执行轨迹 x_i(t) 在 [s_i, e_i] 内，e_i = s_i + d_i。

### 约束
1. 时序约束： s_i ≥ max_{k∈pred(i)} e_k
2. 资源约束： 若 assign(i)=p_k，则 r_i ≤ c_k 且 [s_i, e_i] 与 O_k 不冲突。
3. 安全约束： ∀t∈[s_i,e_i], ∀j, ||x_i(t)-o_j(t)|| ≥ δ_s
4. 部署约束： s_i ≥ release_k + l_k

### 耦合变量
- 避障延时 Δ_i ≥ 0，由 VO 冲突检测产生。
- 修正时间窗口： [s_i', e_i'] = [s_i+Δ_i, e_i+Δ_i]
- 端口成本： cost(i,k) = α·wait(k) + β·l_k + γ·Δ_i·I_conflict

目标 min Σ cost(i,assign(i)) 受约束 1-4。

### 算法骨架
离线：构建任务 DAG → 时序规划生成初始窗口 → 基于匈牙利算法的初始端口分配。
在线：VO 检测 → 若冲突则计算最小 Δ_i → 局部重规划窗口 → 端口匹配重新平衡 → 执行。

本轮在 idea 区保留直觉与形式化，完整算法步骤、复杂度、正确性与风险置于产物区。

# 第 1 轮产物 · TPD-MPD 完整算法设计

## 0. 结论
TPD-MPD 在同一框架内统一层次时序规划、VO 动态避障与多端口稳定部署。离线生成初始可调度方案，在线通过避障延时 Δ 反馈触发局部重规划与端口重匹配，保证安全与可行同时维持端口负载均衡。退化链完整：无障碍时退化为静态规划+匹配；端口单一时退化为规划+避障。

## 1. 符号定义

- T={t_i}, d_i, r_i, pred(i), deadline_i
- P={p_k}, c_k, l_k, O_k
- o_j(t), v_o, δ_s
- x_i(t), s_i, e_i
- VO_i(t) = {v | ∃j, ||x_i+v·τ - o_j(t+τ)|| < δ_s, τ∈[0,τ_h]}
- Δ_i ≥0 避障延时, ε_t 时间裕量
- cost(i,k) = α·idle(k) + β·l_k + γ·Δ_i

## 2. 算法步骤

### 2.1 离线预处理
1. 构建任务 DAG G(T,E)，拓扑序生成。
2. 时序规划：采用约束传播 + 最小松弛求解 s_i, e_i 满足时序与 deadline。
3. 端口初始分配：构建代价矩阵 C[i,k]=cost(i,k) 基于估计 wait, 求解线性分配问题得 assign0。

### 2.2 在线循环每 Δt
```
observe o_j(t), update VO_i
for each active task i:
    if v_i ∈ VO_i(t):
        Δ_i = min τ s.t. v_i ∉ VO_i(t+τ)
        s_i' = s_i + Δ_i; e_i' = e_i + Δ_i
        propagate to succ(i)
        if e_i' > deadline_i:
            trigger局部重规划
    else:
        Δ_i = 0
re-balance ports:
    if max_k load(k) - min_k load(k) > θ:
        run stable matching with updated cost
execute with clipped velocity
```

伪代码片段见思想区骨架。关键不变性：只增触发不做否决，Δ_i 单调非减。

## 3. 复杂度分析

- 离线 DAG 构建 O(n+e)
- 时序规划 约束传播 O(n·w) w 为窗口数
- 端口分配 匈牙利 O(n^2 m) 或 O(n^3) 当 m≈n
- 在线 VO 检测 O(a·b) a 活跃任务数, b 障碍数, 通常 a,b ≤ 50 → <1ms
- 局部重规划采用增量 Bellman-Ford O(|E|·|V|)

整体在线开销 < 5ms @ 200Hz 控制环，离线训练零 GPU。

## 4. 正确性论证

命题 1 安全：若 VO 检测正确且 Δ_i 按定义最小化，则 ∀t, ||x_i(t)-o_j(t)|| ≥ δ_s。
证明：VO 定义为碰撞速度锥，退出锥需至少 Δ_i 时延，修正后速度 v_i ∉ VO_i(t+τ), τ≥0，故距离保持。

命题 2 可调度保持：局部重规划仅在时序约束下平移窗口，pred 关系保持单调，故若初始方案可行，则修正后方案仍满足 s_i ≥ max pred e_k。

命题 3 端口不冲突：分配阶段保证 [s_i, e_i] 与 O_k 不相交，匹配算法保持不变。

失效模式：VO 预测误差导致 Δ_i 低估 → 安全降级为紧急停止；端口延迟骤增导致 deadline 超 → 回退到单端口保守模式。

## 5. 已知风险

- 动态障碍速度上界 v_o 估计偏乐观 → VO 侵入。
- 端口异构延迟 l_k 时变 → 匹配成本漂移。
- 任务链过长导致级联延时爆炸。
- 多端口时钟同步误差导致窗口重叠。

缓解：速度上界保守化 + 观测噪声膨胀；端口延迟在线估计与成本自适应；级联延时设置阈值触发全局重规划；PTP 时钟同步。

## 本轮最大风险一句话
端口异构延迟与动态障碍预测误差耦合导致重规划震荡，进而产生分配抖动与执行抖动，若无延时账本与 VO 保守裕量会破坏安全不动性。
