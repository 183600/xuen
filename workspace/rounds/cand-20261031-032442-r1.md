# 第 13 轮 · SCENE-MEMORY：把 63k 条开源演示变成「场景索引记忆」，用检索重排 + 5 步伺服补上泛化与最后 3 厘米

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份确认：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API；不是其他同名 UniBot。本轮是灵感循环第 3 轮，三个词是「开源硬件」「场景驱动创新」「通用操作」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是把第 12 轮的 DG-KEYFRAME 从「关键帧目标检索」升级为「全轨迹场景记忆 + 候选重排」，并把 2026 年 10 月新公开的 60 个 Dex1 任务接进来。

## 0. 先纠偏：29.7% 的榜首数字当前不可复现，但数据比第 12 轮多了近一倍

第 12 轮记录了 8 个模型的预览榜单（MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9% 等）。本轮复核时发现：**官网排行榜当前不可用**——此前抓取显示排行榜页回到「即将发布 Coming Soon」、`runs.html` 空表；本轮用 curl 复核时，首页/排行榜/`runs.html` 均返回 HTTP 567 的 HTML 兜底页，`leaderboard_data.json` 同样返回 567 而不是 JSON [S1][S3][S4][S5]。也就是说，截至 2026-10-31，那份 8 模型表**无法从公开站点复现**；第 12 轮已经用 `step~success` 回归和跨模型任务相关性证明它更像脚本生成的预览数据，本轮的站点状态进一步支持「不能把它当 SOTA、不能拿它做任务难度表」的判断。

但另一侧发生了真正重要的变化：**开源数据变多了，而且变新了**。

- 挑战赛 32 任务合集：**33,276 episodes / 18,282,246 frames / 169.3 h**，32 个 repo 的 `lastModified` 集中在 **2026-10-14** [S12]。
- 官方 `UnifoLM_G1_Dex1_Dataset` 合集：**72 个 repo / 29,892 episodes / 18,834,191 frames / 174.4 h**；其中 **60 个 repo 是 2026-10 新放出的，合计 26,850 episodes / 152.7 h**，包含 `Hang_Pants`、`Assembling_Motor`、`Pour_Drink`、`Two_Robot_Clean_Table_Left/Right`、`DualRobot_Clean_Table` 等新任务 [S13]。
- 两个合集按 repo 相加约 **63,168 episodes / 343.7 h**（未做任务语义去重），是第 12 轮所知 33k 的近两倍。
- 官方 WLA-1.0 Base 与微调/LoRA 代码已于 **2026-09-28** 开源；WMA-0 的训练、推理、权重也已开源 [S15][S16][S19]。

所以本轮的判断不是「数据不够，去搞更大的模型」，而是：**数据已经足够多，缺的是把数据按比赛真正考的 5 类泛化轴组织起来的记忆层，以及把记忆接到接触执行上的控制层。**

## 1. 重新理解比赛：10 次 trial 全部是泛化 trial，没有 nominal

参赛手册写得很清楚：每个任务 10 次独立运行，包含 5 种泛化类型，每种各 2 次——位置、干扰物、桌面背景、未见物品、人为干扰 [S11]。5×2=10，这意味着：

> **每个任务的 10 次 trial 都属于某一种泛化设定；没有额外的「正常/名义」trial。**

这条事实改变了整个优化目标。过去大家默认「先把 32 个任务在训练分布上做高，再补泛化」；但比赛的实际分布是 **100% OOD**，而且 5 类各占 20%。如果某类泛化是 0%，你不是「差一点」，而是直接丢掉 6.4 个任务当量（32×20%）。反过来，任何一类从 0 提到 30pp，全局就是 **+6pp**（0.2×30）。

于是问题变成：

1. **位置泛化**：目标物/放置区移动后，绝对轨迹失效；需要相对目标 + 在线重定位。
2. **干扰物泛化**：场景多出无关物体；需要任务相关物体的选择与忽略。
3. **背景泛化**：桌布颜色/纹理变化；需要视觉归一化或背景无关的表征。
4. **未见物品泛化**：同类但外观不同的物体；需要形状/功能层面的泛化，而不是记住颜色。
5. **人为干扰泛化**：执行中物体被移动；需要检测「世界变了，而且不是我的动作造成的」，然后重定位/重规划。

第 12 轮的 CHUNK-SERVO 解决的是第 1 类的一部分（位置）和第 3 个「1 秒」（接触闭环）；它没有系统解决 2/3/4/5。本轮要把这 5 类统一到一层**非参数记忆**上。

## 2. 头部方案的共同瓶颈：都在「预测动作」，没人认真「检索经验」

榜单分数不可复现，但头部名字对应的公开技术路线是真实的，可以分析：

| 模型家族 | 公开路线 | 真实优势 | 与本轮相关的瓶颈 |
|---|---|---|---|
| **MolmoAct2** | Ai2 的 action reasoning model；Molmo 2-ER + action expert + adaptive depth reasoning | 3D/空间语义强、推理快、双臂 | 仍是开环 chunk；接触段最后 3cm 的修正与恢复 |
| **WALL-OSS-0.5** | X Square 4B VLA（3B VLM + action expert） | 预训练可用、progress 高 | progress ≠ success；最后一步失败就 0 分；4B 实时性 |
| **DreamZero** | 14B Wan2.1 video-diffusion world-action model | 长程预测/规划 | 14B 推理重；世界模型不直接解决「现在偏了 2mm」；1 秒 chunk 更危险 |
| **π0.5** | Physical Intelligence 开放世界泛化 VLA | 语义/新场景泛化 | 接触密集任务精度；远程部署延迟 |
| **GigaBrain-0** | 世界模型生成数据 + VLA | 数据效率/泛化 | 生成数据物理保真度；最后 3cm |
| **GR00T N1.5** | NVIDIA 通用人形 VLA | 生态/embodiment | 任务特定精度；数据覆盖 |

共同点不是「模型不够大」，而是：

- **它们都把成功经验压进权重，测试时不再查经验。** 63k 条演示只被用来做梯度，没有被当成一个可检索的「行为记忆」。
- **它们都用 action chunk 开环执行。** chunk 内不看新图；接触、插入、挂杯、拉拉链恰好发生在 chunk 内部。
- **它们都没有为 5 类泛化轴设计显式的索引/路由。** 位置变了靠泛化，背景变了靠泛化，人来干扰也靠泛化；但泛化不是免费的。
- **单模型规则堵死了「再加一个学习残差」的捷径**，但没有堵死「非参数记忆 + 确定性控制器」。

所以本轮的切入点不是「再训一个更大的 VLA」，而是：

> **让冻结的 VLA 负责提出候选动作，让 63k 条成功演示组成的场景记忆负责重排候选，让 5 步视觉伺服负责最后 3 厘米。**

一句话：**VLA proposes, memory disposes, servo executes.**

## 3. 为什么是「检索记忆」，而不是「世界模型」或「更大模型」

### 3.1 检索记忆的三个结构性优势

1. **它是非参数的，天然合规。** 记忆库没有学习权重，不需要第二个策略网络；候选重排是确定性评分函数。单模型规则下，这比「再加载一个残差策略/检索网络」安全得多。
2. **它直接利用 63k 条成功演示。** 这些演示里已经包含了大量位置、物体、背景的自然变化；把它们索引起来，比让 6B 模型在 169h 上重新压缩一遍更省算力，也更可解释。
3. **它可以按 5 类泛化轴建索引。** 同一个任务的成功轨迹，可以按「物体相对位姿」「背景描述子」「干扰物数量」「目标外观」「是否有人」切成不同视图；测试时先判断当前属于哪一类，再取对应的记忆。这是「场景驱动」的直接落地。

### 3.2 与近期工作的差异

2026 年检索增强 VLA 已经很活跃：Retrieval-VLA 用稀疏物体关键点 + 轻量 cross-attention 做 training-free 适配 [S22]；R2A 用运动基元图 + 学习的 GNN 门控，公开摘要称真实世界最高 +40% [S23]；Retrieve-then-Steer 用在线成功记忆 + flow-matching 先验注入 [S24]；RA-VLA 用行为对齐的检索器 [S25]。这些工作证明「检索能救 OOD」，但也暴露了两个问题：

- 它们大多需要一个**学习的检索器/门控/分割模型**（Grounded SAM、GNN、cross-attention），在「单模型」规则下有解释风险；
- 它们大多只用**视觉相似度**检索，背景/干扰物一变，检索就被稀释；而比赛恰恰考背景和干扰物。

本轮的差异是：

- **几何优先，而不是像素优先**：用物体相对位姿/SE(3) 对齐，而不是整图 embedding；背景/干扰物不进入检索键。
- **场景因子化索引**：按 5 类泛化轴分片，先路由再检索。
- **候选重排，而不是直接融合**：VLA 采样 K 个 chunk，记忆只做「裁判」，不直接产生动作；置信度低时回退 VLA。
- **无学习权重的记忆 + 确定性重排**：不需要训练第二个模型；描述子可用 ORB/颜色/深度，或用同一个 VLA checkpoint 的 encoder（C3 合规模式）。
- **接到 CHUNK-SERVO**：记忆解决「往哪走」，伺服解决「最后 3cm 怎么贴上去」。

### 3.3 为什么不是世界模型

世界模型（DreamZero、WMA-0、GigaBrain-0）解决的是「想象未来」，不是「现在偏了 2mm」。在 30Hz、远程 RTT 100ms、单次 180s 的设定下，14B 视频扩散的推理成本与延迟都不划算；而 5 类泛化轴里，位置/背景/干扰物/人为干扰都不需要生成未来视频，只需要「检索相似经验 + 重定位 + 重排」。所以本轮把世界模型降级为**观察项**：只考虑用 WMA-0 做离线数据增强（M7），不作为在线策略。

## 4. 方案：SCENE-MEMORY 的三层

### 4.1 第一层：离线场景记忆

对 63k 条演示（挑战赛 32 任务 + Dex1 72 任务）做统一索引：

- 按任务/阶段切关键帧：抓取前、抓取、搬运、预放置、接触、释放；用 FACT-VLA 的相位分割 + 夹爪开合/EE 速度做边界。
- 每帧存：任务 ID、语言、相位、左右 EE 位姿、夹爪开度、未来 30/60 步 EE 轨迹、物体在 base 系的位姿、物体相对 EE 轨迹 `T_obj_ee(k)`、腕部目标图、背景描述子、干扰物数量、场景标签。
- 建四层索引：任务+相位 → 物体相对位姿桶 → 场景标签 → 视觉/几何描述子。检索时先硬过滤任务/相位，再按几何/场景重排。
- 规模估算：33k 挑战赛 + 30k Dex1，按每 10 帧一个关键帧约 0.5–1.5M 条；每条轨迹 30×6 float + 描述子，压缩后 <20GB；腕部缩略图另计 <100GB。

### 4.2 第二层：在线场景路由 + 检索重排

- **场景路由**：用确定性特征判断当前 trial 更像哪一类泛化——桌面平面颜色/纹理直方图 vs 训练分布（背景）、任务无关物体数量（干扰物）、目标物相对位姿是否落在演示分布的 90% 椭圆外（位置）、目标外观描述子距离（未见物品）、头部图像中的人手/运动残差（人为干扰）。输出一个多热标签，不要求互斥。
- **检索**：`task + phase + object_pose_bucket + scenario_tag` 过滤，取 top-k（k=8–16）；用物体相对位姿/腕部目标图重打分。
- **对齐**：把检索到的相对轨迹变换到当前物体位姿：`T_base_ee^d(k) = T_base_obj(t) · T_obj_ee^e(k)`；物体位姿不可靠时退回「相对当前 EE」对齐。
- **候选重排**：VLA 一次采样 K 个 30 步 chunk（扩散/flow 模型天然可多采样）；每个候选与检索轨迹做 DTW/Procrustes 对齐，再叠加目标进度、平滑性、夹爪时序、安全项；选最高分。置信度低 → 回退 VLA 的 top-1。
- **记忆不产生动作**：它只对 VLA 的候选打分；这保证了「唯一学习模型」仍然是 VLA。

### 4.3 第三层：CHUNK-SERVO 执行 + 人为干扰恢复

- 选中的 30 步 chunk 切成 6 个 5 步执行块；每个块用腕部/头部视觉做一次 IBVS/PBVS 修正；接触段法向缩幅、切向保留；RTT 用 Smith 预测/增益调度补偿。
- 编辑检测（GEO-RESIDUAL）触发时：停 → 重新估计物体位姿 → 重新检索/对齐 → 若目标可见则继续，不可见则 VLA 重规划；重试上限内失败则安全退出。
- 这样，位置泛化由「相对目标 + 检索对齐」负责，背景/干扰物由「场景路由 + 几何检索」负责，未见物品由「VLA 语义 + 相对轨迹」负责，人为干扰由「编辑检测 + 重检索」负责，接触精度由「5 步伺服」负责。

## 5. 三个灵感词怎么落地

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **开源硬件** | 用官方开源的 G1/Dex1 数据（63k eps / 344h）、WLA/WMA 权重、IsaacLab/MuJoCo 仿真做记忆与验证；用 OPEN-PROBE 低成本的 G1 相机几何 + 桌面夹具复现 5 类扰动，做本地场景风洞 | 不自己造一台人形机器人；不假设低成本机械臂能替代 G1 做策略训练 |

## 6. 与第 10–12 轮的关系：保留、升级、剪枝

**保留**：

- FACT-VLA 的相位化 BC、CAC 柔顺执行、EGP 证据门控；
- GEO-RESIDUAL 的动作条件化残差、米制表面距离、编辑检测；
- CHUNK-SERVO 的双频执行、相对目标、5 步伺服、RTT 标定；
- 官方 WLA 基座、33k 演示、单任务不计分通道。

**升级**：

- DG-KEYFRAME（关键帧目标）→ **SCENE-MEMORY（全轨迹 + 候选重排）**；
- 单一 nominal 数据 → **63k 演示 + 60 个 Dex1 辅助任务 + 场景因子化索引**；
- 「最后 3 厘米」→ **5 类泛化轴 + 最后 3 厘米** 的统一诊断；
- 记忆只做目标 → **记忆做裁判**（VLA 出候选，记忆重排）。

**剪枝**：

- 不再用榜单任务排名做优先级（榜单当前不可复现）；
- 不再从零训 6B/14B（官方 WLA/WMA 已开源）；
- 不做完整 sim-to-real 策略训练（只做控制器/场景风洞）；
- 不做第二个学习检索器/残差策略（单模型风险）；
- 不做 6D 物体位姿网络（透明/变形不可靠；用相对位姿 + 局部特征）；
- 不做力/触觉闭环（API 没有）；
- 不做 30Hz 广域网伺服（RTT 不允许；5 步块）；
- 不把「世界模型」当在线策略（只保留离线数据增强观察项）。

# 第 13 轮产物 · SCENE-MEMORY 技术报告与创新点清单

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「SCENE-MEMORY」的工程化产物；保留第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，把 DG-KEYFRAME 升级为「全轨迹场景记忆 + 候选重排」，并接入 2026-10 新公开的 60 个 Dex1 任务。

## 0. 结论与边界

### 0.1 一句话结论

比赛每个任务的 10 次 trial 全部是泛化 trial（5 类 ×2），而官方 63k 条成功演示只被当作梯度数据、没有被当作可检索的行为记忆；把演示按「任务/相位/物体相对位姿/场景标签」建成非参数记忆，让冻结的 WLA 采样多个候选 chunk、让记忆做确定性重排、让 5 步视觉伺服做接触闭环，可以在不新增第二个学习模型的前提下，同时改善位置/背景/干扰物/未见物品/人为干扰五类泛化，并把最后 3 厘米从开环变成闭环。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、HF API 直接核实 | 5 类泛化 ×2、180s、单模型、33,276 eps、WLA chunk 30@30、API 无深度/力 |
| B | 我们在公开数据/网页上做的统计/分析，可复现 | 63,168 eps / 343.7h 的合集相加、32 任务 episode 分布、榜单 JSON 返回 567 |
| C | 设计假设，需 G0–G8 验证 | 记忆重排 +10pp、场景路由 ≥80%、5 步伺服稳定域、OPEN-PROBE 可迁移性 |

本轮没有真机评测/模型训练结果；已完成的是公开数据/页面审计（A/B）和设计推演（C）。§6 的 G0–G8 是待执行实验设计，不是已得结果。

### 0.3 本轮不做什么

- 不从零训 6B/14B VLA/World Model；官方 WLA-1.0 Base 与 WMA-0 已开源。
- 不做完整 sim-to-real 策略训练；仿真只做控制器风洞与场景风洞。
- 不做第二个学习检索器/残差策略/GNN 门控；记忆是数据库，重排是确定性评分。
- 不做 6D 物体位姿网络；用双目几何 + 相对位姿 + 局部特征，透明/变形任务回退。
- 不做力/触觉闭环；API 没有。
- 不做逐任务策略；规则禁止，且不泛化。
- 不做 30Hz 广域网伺服；用 5 步块/双频。

## 2. 诊断：100% 泛化 trial 与三个缺口

### 2.1 评分分解

总分：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

若每类泛化轴等权（2/10），则：

```math
S = \frac{1}{5}\sum_{a\in\{P,D,B,U,H\}} \bar p_a,
```

其中 `\bar p_a` 是 32 任务在该轴上的平均成功率。任何一轴 +30pp → 全局 **+6pp**；任何一轴 0% → 全局最多 80%（如果其余四轴 100%）。

320 trials 下，若 `p≈0.25`，单次标准误约：

```math
\mathrm{SE}(S)\approx \sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

所以 +1–2pp 不能当结论；必须配对 A/B + bootstrap CI。设计目标应放在 +5pp 以上，或单轴 +15pp 以上。

### 2.2 五轴 → 五种失败机制

| 泛化轴 | 测试怎么变 | 典型失败 | 对应干预 |
|---|---|---|---|
| **位置 P** | 目标物初始位置/放置区移动 | 绝对轨迹失效；抓空/放偏 | 相对目标 + 物体重定位 + 记忆对齐（M1/M2） |
| **干扰物 D** | 场景多出无关物体 | 抓错物体；注意力被稀释 | 任务物体假设 + 几何检索 + 场景路由（M1/M3） |
| **背景 B** | 桌布颜色/纹理变化 | 视觉表征漂移；抓取点偏移 | 深度分割 + 色度归一化 + 背景无关检索（M4/M1） |
| **未见物品 U** | 同类但外观不同的物体 | 语义/形状泛化失败；抓取点不对 | VLA 语义 + 相对轨迹 + 辅助任务（M3/M1） |
| **人为干扰 H** | 执行中物体被移动 | 继续执行旧轨迹；撞/掉 | 编辑检测 + 重定位 + 重检索（M5/M1） |

### 2.3 三个缺口

1. **场景缺口**：训练数据 nominal，测试 100% OOD；没有显式的场景索引/路由。
2. **接触缺口**：30 步 chunk 开环，最后 3cm（插入/挂/叠/拉链/锁）没有闭环。
3. **恢复缺口**：人移动物体后，策略继续执行旧计划；没有「世界变了」的检测与重规划。

第 12 轮的 CHUNK-SERVO 补的是第 2 个缺口的一部分；第 11 轮的 GEO-RESIDUAL 补的是第 3 个缺口的检测；本轮用 SCENE-MEMORY 把第 1 个缺口和「检索」接起来，并把三者串成一条链。

### 2.4 为什么不是更大的模型

- 官方 WLA 已经 6B/2,500h/64 任务；从零训 6B/14B 的边际收益远低于执行层/记忆层。
- 模型越大，chunk 往往越长，越不反应；与接触精度直接冲突。
- 世界模型解决「想象未来」，不解决「现在偏了 2mm」；在线视频扩散的延迟不适合 30Hz 远程评测。
- 单模型规则下，加一个学习检索器/GNN 门控有合规风险；非参数记忆 + 确定性重排没有。
- 比赛 5 类泛化轴是**结构化**的；结构化问题用结构化索引，比「更大模型 + 祈祷泛化」更划算。

## 3. 方法：SCENE-MEMORY

### 3.1 总架构

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)       │
                    │  ├─ phase observer (FACT-VLA)       │
                    │  ├─ scene router (deterministic)    │
                    │  ├─ object pose (stereo/ICP)        │
                    │  ├─ memory query + rerank           │
                    │  ├─ CHUNK-SERVO                     │
                    │  └─ action adapter (WLA 54D → API)  │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared VLA server (GPU)            │
                    │  UnifoLM-WLA-1.0, 30-step samples   │
                    └─────────────────────────────────────┘
```

- 每个端口一个 `PolicyService` 实例，独立 `reset()`、独立相位/记忆状态。
- 记忆库只读，N 端口共享（copy-on-write/只读 mmap）；不抢 GPU。
- VLA 请求异步、可批处理；`get_action` 不阻塞（除冷启动）。
- 唯一学习模型是 VLA；记忆/路由/重排/伺服都是确定性组件。

### 3.2 离线记忆构建

```python
for episode in datasets:                     # 63k episodes
    phases = segment_phases(episode)         # FACT-VLA + gripper/EE heuristics
    for phase in phases:
        for k in keyframes(phase, stride=10):
            ee = episode.ee_pose[k]          # left/right, base frame
            obj = estimate_object_pose(episode, k)   # stereo/ICP, optional
            future = episode.ee_pose[k:k+H]  # H=30 or 60, base frame
            if obj.valid:
                rel = inv(obj.T) @ future    # object-relative trajectory
            else:
                rel = inv(ee) @ future       # EE-relative fallback
            memory.add(
                task=episode.task, language=episode.language,
                phase=phase.id, frame=k,
                ee=ee, rel=rel, obj=obj,
                gripper=episode.gripper[k:k+H],
                wrist=episode.wrist[k], head=episode.head[k],
                bg=background_descriptor(episode.head[k]),
                distractor_count=count_distractors(episode, k),
                human=detect_human(episode.head[k]),
                quality=episode.success and smoothness(future),
            )
```

关键点：

- **存观测轨迹，不存原始 action**：避免 WLA 54D 与挑战赛 21D 的 action-space 不一致；EE 轨迹可直接转成 `ee` 模式的绝对目标位姿。
- **物体相对轨迹**：`T_obj_ee(k) = T_base_obj^{-1} T_base_ee(k)`；位置/人为干扰时，物体位姿变，期望轨迹跟着变。
- **关键帧**：每 10 帧 + 相位边界；33k+30k eps 约 0.5–1.5M 条；轨迹 30×6 float + 元数据，压缩后 <20GB；腕部 128×128 JPEG 另计 <100GB。
- **质量分**：成功、平滑、无碰撞、无遮挡；低质量帧不进入 top-k。

四层索引：

1. 任务 + 相位（硬过滤）；
2. 物体相对位姿桶（3D 网格 + 朝向 bin，软过滤）；
3. 场景标签（背景簇/干扰物数量/人）；
4. 视觉/几何描述子（ORB/颜色/深度；或同一 VLA encoder，C3）。

### 3.3 在线检索与对齐

```python
def retrieve(obs, task, phase, obj_pose, scene_tags, k=16):
    cand = index.filter(task=task, phase=phase)
    cand = cand.score_by_pose(obj_pose, top=200)
    cand = cand.boost(scene_tags)
    cand = cand.topk(k)
    return rerank(cand, obs, obj_pose)
```

对齐：

```math
T^{B,d}_{E}(u) = T^{B}_{O}(t)\; T^{O,e}_{E}(u)
```

其中 `T^{B}_{O}(t)` 是当前物体在 base 系的位姿，`T^{O,e}_{E}(u)` 是演示中物体相对 EE 的未来轨迹。物体位姿不可靠时：

```math
T^{B,d}_{E}(u) = T^{B}_{E}(t)\; T^{E(t),e}_{E}(u)
```

即「相对当前 EE」对齐；这能处理位置平移，但不能处理物体旋转/换向。

### 3.4 候选重排

VLA 一次采样 K 个 30 步 chunk（扩散/flow 可多采样；若模型服务器只返回一个，改成返回 K 个，仍是同一模型）。对每个候选 `A_i`：

```math
\mathrm{score}(A_i) =
w_1 e^{-\mathrm{DTW}(A_i, A_{\mathrm{mem}})/\sigma}
+ w_2\,\mathrm{goal}(A_i, A_{\mathrm{mem}})
+ w_3\,\mathrm{smooth}(A_i)
- w_4\,\mathrm{risk}(A_i)
```

- `DTW`：对 EE 平移/旋转分别做动态时间规整，允许速度差异；
- `goal`：候选末帧与记忆末帧在物体相对系的位姿一致性；
- `smooth`：jerk/加速度惩罚；
- `risk`：关节限位、碰撞代理、夹爪时序异常；
- 置信度 `c = max_i score_i - second_i`；`c` 低 → 回退 VLA top-1 或做候选平均。

**为什么是重排而不是直接融合**：直接融合会把记忆的轨迹形状强加到 VLA 上，遇到未见物品/变形任务会拖累；重排只在 VLA 的候选里选，保留 VLA 的语义/泛化，记忆只做「哪个候选更像成功经验」的裁判。

### 3.5 CHUNK-SERVO 执行

- 选中的 30 步 chunk → 6 个 5 步执行块；每块用腕部/头部视觉做一次 IBVS/PBVS 修正。
- 动作空间用 `ee`：`a_cmd = a_ff ∘ exp(Δ)`，`Δ = clip(K_p e + K_d ė, ±δ_p, ±δ_r)`；每块最多 1cm/0.05rad。
- 接触段：`Δ = Δ_n + Δ_t`；法向乘 0.3–0.5 并低通，切向保留；`r_grasp` 突变 → 滑移 → 重抓。
- 延迟：测 RTT `τ`，用 Smith 预测/增益调度；`τ>150ms` 或 `T_fb>300ms` → 关 IBVS，只做 PBVS 粗对齐 + VLA。
- 回退：物体位姿/腕部特征置信度低 → 跳过伺服，执行 VLA 原 chunk。

### 3.6 人为干扰恢复

```text
if edit_score > θ_e for K frames:
    hold position
    re-localize T_base_obj with head stereo
    if target visible:
        re-query memory with new object pose
        resume servo with conservative gain
    else:
        request VLA re-plan with new image + language
    if retries > max: fail gracefully
```

`edit_score` 来自 GEO-RESIDUAL：机器人动作解释不了的场景运动。人为干扰轴占 20%；这是性价比最高的单项之一。

### 3.7 场景路由

确定性特征（不加载第二个学习模型）：

| 轴 | 特征 | 判定 |
|---|---|---|
| 背景 B | 桌面平面颜色/纹理直方图 vs 训练分布 | Mahalanobis 距离 > θ_b |
| 干扰物 D | 工作区任务无关物体数量/占位 | 数量 > 任务先验 + θ_d |
| 位置 P | 目标物相对位姿 vs 演示分布 | 落在 90% 椭圆外 |
| 未见物品 U | 目标外观描述子 vs 任务已知物体 | 距离 > θ_u |
| 人为干扰 H | 头部图像人手/运动残差 | 人手检测或 edit_score > θ_h |

输出多热标签；标签用于三处：VLA prompt 的场景前缀（训练时做 tag dropout）、记忆检索的 boost、CHUNK-SERVO 的增益调度。标签错了不至于灾难，因为记忆/伺服都有置信度回退。

### 3.8 合规性

| 组件 | 是否有学习权重 | 合规说明 |
|---|---|---|
| VLA | 是（唯一） | 官方 WLA 微调/冻结 |
| 记忆库 | 否 | 演示轨迹 + 元数据 + 确定性描述子 |
| 场景路由 | 否 | 颜色/深度/几何/运动残差阈值 |
| 候选重排 | 否 | DTW/Procrustes/平滑/安全评分 |
| CHUNK-SERVO | 否 | IBVS/PBVS 控制律 |
| 描述子（可选） | 同一 checkpoint | 用 VLA encoder，不加载第二个模型（C3） |

**禁止**：在线加载第二个策略/残差网络/独立视觉编码器/GNN 门控/Grounded SAM。离线可以用工具做标注，但不进入提交包。

### 4.2 场景因子化增强

不追求「生成以假乱真的视频」，只做**动作一致/几何一致**的低成本增强：

1. **背景替换（B）**：头双目 RANSAC 桌面平面 → 只替换桌面色度/纹理，保留亮度、阴影、反光；训练时随机从纹理库采样；测试时可选做保守归一化。
2. **干扰物复制粘贴（D）**：从其他 episode/数据集中分割小物体，按深度估计尺度，贴到桌面空白区；保留阴影/遮挡顺序；动作标签不变（干扰物不在任务轨迹上）。
3. **位置 SE(2) 变换（P）**：把目标物 + 轨迹整体平移/旋转；用深度重投影或仿真重渲染；动作轨迹做同样的刚体变换；只对平移等变的任务启用。
4. **物体外观替换（U）**：用额外 60 任务/开源 3D 资产替换目标物外观，保持几何/抓取点；用分割 + 图像修复；动作标签不变。
5. **人手/他机干扰（H）**：在图像中叠加人手/另一只机械臂；或直接用 `Two_Robot_Clean_Table_Left/Right`、`DualRobot_Clean_Table` 数据做「他机」代理；恢复标签来自重定位，不要求模仿具体恢复轨迹。

所有增强都带「增强类型」标签；训练时按 5 轴平衡采样，并做 tag dropout（10–20%），避免模型依赖场景标签。

### 4.3 60 个 Dex1 辅助任务

- 目的：给 VLA 更多物体/技能/背景，提升未见物品与通用操作；给记忆更多「相似成功行为」。
- 方式：多任务联合微调（32 主任务 + 60 辅助任务），辅助任务损失权重 0.2–0.5；场景平衡采样；按任务/物体分组验证。
- 风险：负迁移、任务标签噪声、计算；先做 5–10 个辅助任务的 pilot，确认不回归再扩。
- 不把辅助任务当测试；只用挑战赛 32 任务做最终评测。

## 5. OPEN-PROBE：开源硬件场景探针

### 5.1 动机

当前没有可信的公开榜单，真机评测名额有限；需要一个**低成本、可复现、能注入 5 类扰动**的本地风洞，用来：

- 标定场景路由（背景/干扰物/人手检测）；
- 验证记忆对齐（物体位姿估计、相对轨迹变换）；
- 演练人为干扰恢复；
- 做单任务通道之前的快速回归。

它**不是**策略训练平台，也**不假设**低成本机械臂能替代 G1；它只验证「感知/路由/记忆/伺服」这些与 embodiment 相对无关的模块。

### 5.2 BOM 与几何

| 件 | 规格 | 作用 |
|---|---|---|
| 双目相机 | 2× 全局快门 RGB（D435/D405/OAK-D），基线 58.25mm | 复现 G1 头双目几何 |
| 支架 | 铝型材 + 3D 打印 | 相机高度/俯仰可调 |
| 桌面 | 1m×0.6m，可换桌布 | 背景泛化 |
| 夹具 | 3D 打印杯架/试管架/网口/充电器/碗 | 任务几何 |
| 干扰物 | 20–30 个不同形状/颜色小物 | 干扰物泛化 |
| 人手/他机 | 手套 + 假手；可选 SO-101 | 人为干扰/他机代理 |
| 标定 | 棋盘格/ArUco | 内参/外参/重投影 |
| 采集 | 笔记本/边缘 GPU | 同步、标定、回放 |

成本约 **$800–1,500**；搭建 1–2 周。相机基线/高度/俯仰按 G1 数据里的 `state_d435` 与头双目参数复现；不追求外观 1:1，追求**几何/视角/尺度**接近。

### 5.3 实验

| 实验 | 方法 | 通过标准 |
|---|---|---|
| 相机标定 | 棋盘格 + 重投影 | ≤5px |
| 物体位姿 | 已知位姿放置，估计 vs 真值 | ≤5mm/2° |
| 背景路由 | 10 种桌布，采集 200 帧 | 准确率 ≥80%，误报 ≤10% |
| 干扰物路由 | 0–5 个干扰物 | 数量误差 ≤1，分类 ≥80% |
| 人手检测 | 人手进入/离开 | 检测延迟 ≤200ms |
| 记忆对齐 | 物体平移/旋转，比较 DTW | 对齐误差 ≤2cm/5° |
| 恢复演练 | 人移动物体，脚本恢复 | 恢复成功 ≥70%（受控） |

### 5.4 边界

- 不验证 G1 的动力学/夹爪力控；不预测真机绝对成功率。
- 不训练策略；只做感知/路由/记忆/伺服的单元测试。
- 低成本臂的形态与 G1 不同；跨 embodiment 只用于「检索几何是否成立」，不用于策略迁移。
- 若时间不够，优先做「双目标定 + 背景/干扰物路由 + 记忆对齐」三项，人手/他机后置。

### 6.2 单任务通道 A/B

| 项 | 设计 |
|---|---|
| 任务 | PlugInEthernet（插入）、HangCup（挂）、ZipUp（拉链）、StackBowls（叠）、FoldTowel（变形，防回归） |
| 次数 | 每任务 5 次 A/B（memory off/on；servo off/on 分两轮） |
| 初始条件 | 同一位置/背景；尽量配对 |
| 指标 | 成功率、步骤分、耗时、p99 延迟、恢复次数 |
| 通过 | ≥3/5 任务 +10pp；FoldTowel 不回归 >5pp |
| 统计 | 配对差值 + bootstrap 95% CI；5 次/任务只看方向，不宣称显著 |

### 6.3 任务组合

- 先用单任务通道测 5 个代表任务，得到每轴的 `q_a`（失败发生在该轴的比例）和 `Δ_a`（干预增益）。
- 按 `priority_t = q_t × Δ_t / cost_t` 排序；先做 A 档中 `q` 高、`cost` 低的 3–5 个任务。
- 不要一次铺 18 个接触任务；不要用当前榜单排名当难度表。
- 5 轴等权：如果某一轴在单任务通道里完全没有信号，优先补该轴的通用干预（背景/人手），而不是继续抠单任务。

### 6.4 统计

- 320 trials、`p≈0.25` → SE≈2.4pp；配对设计可降方差，但仍需 bootstrap CI。
- 报告：每任务成功率、每轴平均成功率、总平均成功率、步骤分、p50/p99 延迟、timeout、恢复次数。
- 消融用同初始条件配对；不要拿不同批次/不同机器人混在一起比较。
- 若 CI 跨 0，不下结论；继续测或放弃该干预。

### 6.5 门 G0–G8

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | 数据/索引是否可用？ | 32+60 任务元数据完整；关键帧覆盖 ≥95%；物体位姿有效率 ≥70% | 缩小到 32 任务；只做视觉索引 |
| G1 | 记忆检索是否可信？ | 留出集 top-5 含几何有效轨迹 ≥80%；对齐误差 ≤2cm/5° | 改任务级固定轨迹；降低 top-k |
| G2 | 场景路由是否可信？ | 5 轴分类 ≥80%；误报 ≤10% | 只用背景/人手两个高置信轴 |
| G3 | 仿真重排是否涨点？ | 扰动套件 +10pp；p99 检索+重排 ≤100ms | 关记忆；只保留伺服 |
| G4 | 真机单任务是否涨点？ | ≥3/5 任务 +10pp；FoldTowel 不回归 | 不提交 memory 版本 |
| G5 | 人为干扰能否恢复？ | 检测 ≤200ms；仿真恢复 ≥70% | 只做离线标注/不线上触发 |
| G6 | 系统是否稳定？ | N 端口隔离；reset 干净；内存不涨；p99 ≤150ms | 回退基线/加 chunk |
| G7 | 消融是否支持因果？ | 记忆 > 无记忆；场景索引 > 平坦索引；5 步 > 30 步；伺服 > 无伺服 | 保留有效部分，砍无效部分 |
| G8 | 32×10 干跑是否稳定？ | 无端口串扰；无 NaN/形状错；timeout 不升 | 回退安全基线 |

2. 场景因子化索引 vs 平坦索引；
3. 候选重排 vs 直接融合 vs 不融合；
4. 相对目标 vs 绝对目标；
5. 5 步 chunk vs 30 步 chunk；
6. CHUNK-SERVO on/off；
7. 场景归一化 on/off；
8. 人为恢复 on/off；
9. 候选数 K=1/4/8/16；
10. 关键帧 stride=5/10/20。

### 7.2 M1 · SCENE-MEMORY / MEMORY-RERANK（主投）

- **动机**：63k 条成功演示只被当梯度，没有被当记忆；比赛 100% 泛化 trial；VLA 采样有随机性；单模型规则禁止第二个学习模型，但允许非参数记忆 + 确定性重排。
- **与现有方案的差异**：VINN 是最近邻动作检索，没有 VLA 候选、没有场景索引；Retrieval-VLA 用 Grounded SAM + cross-attention（学习模块）；R2A 用 GNN 门控（学习模块）；Retrieve-then-Steer 是在线成功记忆 + flow 先验；本方案是**离线场景因子化记忆 + 冻结 VLA 多候选 + 确定性 DTW/几何重排 + CHUNK-SERVO**，不需要第二个学习权重。
- **技术可行性**：高。离线索引 + FAISS + DTW 都是成熟工程；WLA 扩散头可多采样；挑战赛数据有 EE 位姿/四路 RGB；物体位姿可用双目/ICP，失败则回退。
- **所需资源**：63k eps（挑战赛 811GB + Dex1 约 1–2TB，可按需下载）；关键帧/描述子 <200GB；1×24GB GPU（VLA 推理/微调）；16–32 CPU；2–4TB 存储；1 名几何/检索工程师 + 1 名 VLA 工程师。
- **落地步骤**：数据审计 → 关键帧/相位 → 物体位姿 → 四层索引 → 留出集检索评测（G1）→ VLA 多候选 → 重排（G3）→ 单任务 A/B（G4）→ 全量（G8）。
- **风险**：检索 mismatch（未见物品/透明物体）；物体位姿误差；DTW 延迟；记忆规模；候选多样性不足；单模型解释（需写清楚记忆无学习权重）；数据泄漏。
- **通过门**：G1 top-5 ≥80%、对齐 ≤2cm/5°；G3 +10pp；G4 ≥3/5 +10pp；G7 记忆 > 无记忆。

### 7.3 M2 · CHUNK-SERVO 2.0（主投）

- **动机**：WLA 30 步 chunk = 1 秒开环；接触/插入/挂/叠/拉链/锁发生在最后 3cm；远程 RTT 放大反馈延迟；API chunk 内没有新观测。
- **与现有方案的差异**：第 12 轮已提出 30 步规划 + 5 步伺服；本轮把它和记忆重排串起来：记忆决定「往哪走」，伺服决定「怎么贴上去」；接触段法向缩幅、RTT 增益调度、置信度回退。
- **技术可行性**：高。IBVS/PBVS 是经典控制；头双目有标定；腕部可一次性标定；仿真可扫稳定域。
- **所需资源**：1 名控制/视觉工程师；1 GPU；MuJoCo/IsaacLab；2–3 周。
- **落地步骤**：腕部标定 → IBVS/PBVS → 5 步块 → 接触相位 → RTT 扫描 → 单任务 A/B。
- **风险**：腕部无内参；透明/反光；RTT 高；标定漂移；伺服压过 VLA 语义。
- **通过门**：G4 3/5 +10pp；G6 p99 ≤150ms；G7 5 步 > 30 步。

### 7.4 M3 · SCENE-CURRICULUM（保留）

- **动机**：2026-10 新放出 60 个 Dex1 任务 / 26,850 eps / 152.7h，含更多物体/背景/技能；官方 WLA 只在 64 任务/2,500h 上训过，未必覆盖这些新数据；未见物品/背景/干扰物需要多样性。
- **与现有方案的差异**：不是简单多任务混合，而是**按 5 轴分层采样 + 场景标签 + 辅助任务权重**；用 60 任务做「通用操作」辅助，用 32 任务做主评测；按物体/背景分组验证，避免泄漏。
- **技术可行性**：中高。WLA 微调 24GB 可跑；数据格式兼容；需要数据审计/去重。
- **所需资源**：1–2 GPU 周；2TB 存储；1 名训练工程师；数据审计 1 周。
- **落地步骤**：数据审计 → 场景标签 → 采样器 → 5–10 任务 pilot → 全量微调 → 消融。
- **风险**：负迁移；任务标签噪声；与测试集重叠；计算；过拟合辅助任务。
- **通过门**：G3/G4 不回归；留出场景 +3pp；辅助任务消融有正贡献。

### 7.5 M4 · SCENE-NORMALIZE（保留）

- **动机**：背景泛化占 20%；桌布颜色/纹理变化是纯视觉 domain shift；不需要重训大模型就能改善。
- **与现有方案的差异**：用双目深度 RANSAC 桌面平面，只归一化桌面色度/纹理，保留亮度/阴影/几何；测试时可选择开启；不是全局风格迁移，不改变物体/机械臂。
- **技术可行性**：高。经典几何/图像处理；CPU 可跑；可与记忆检索叠加。
- **所需资源**：1 人周；双目深度；纹理库；无 GPU。
- **落地步骤**：平面分割 → 色度归一化 → 增强训练 → 单任务 A/B（背景轴）。
- **风险**：去掉有用背景线索；反光/透明桌面；阴影/光照不一致；过度归一化。
- **通过门**：背景轴 +10pp；其他轴不回归；视觉检查无伪影。

### 7.6 M5 · HUMAN-REBOUND（保留）

- **动机**：人为干扰占 20%；手册明确「执行过程中临时改变物品位置」；继续执行旧轨迹会撞/掉。
- **与现有方案的差异**：不是「识别人类」，而是「场景动了，而且不是我的动作解释的」；动作条件残差 + 重定位 + 重检索 + 保守恢复；与记忆/伺服共用物体位姿。
- **技术可行性**：高。GEO-RESIDUAL 已有信号；双目/SLAM 可重定位；恢复策略可脚本化。
- **所需资源**：1–2 人周；仿真扰动；1 名控制工程师。
- **落地步骤**：合成扰动 → 检测阈值 → 重定位 → 重检索 → 单任务 A/B。
- **风险**：遮挡；误报；人手不在视野；无 force/tactile；恢复超时。
- **通过门**：G5 检测 ≤200ms、恢复 ≥70%；G4 人为轴 +15pp。

### 7.7 M6 · OPEN-PROBE（观察/支撑）

- **动机**：没有可信榜单，真机名额有限；需要一个低成本、可复现的 5 轴风洞；「开源硬件」灵感词的落地。
- **与现有方案的差异**：不是造人形机器人，也不是 sim-to-real 训练；是**G1 相机几何 + 桌面夹具 + 可换背景/干扰物/人手**的场景探针；只验证感知/路由/记忆/伺服。
- **技术可行性**：中。需要硬件搭建/标定；$800–1,500；1–2 周。
- **所需资源**：双目相机、铝型材、3D 打印、夹具、干扰物、标定板；1 名硬件/视觉工程师。
- **落地步骤**：BOM → 搭建 → 标定 → 背景/干扰物/人手采集 → 记忆对齐测试。
- **风险**：形态差异；不能预测真机成功率；时间；相机同步。
- **通过门**：重投影 ≤5px；物体位姿 ≤5mm/2°；路由 ≥80%；对齐 ≤2cm/5°。

### 7.8 M7 · WORLD-MODEL-AUG（观察）

- **动机**：5 轴需要反事实场景；WMA-0 已开源，可做「仿真引擎/数据生成」；GigaBrain-0 证明世界模型数据有价值。
- **与现有方案的差异**：不作为在线策略，只做离线数据增强；用 WMA-0 对 32 任务做背景/物体/干扰物编辑，生成带动作标签的训练数据；不追求生成视频的保真度，只追求**几何/动作一致**。
- **技术可行性**：低–中。视频扩散训练/推理重；物理保真度未知；需要大量 GPU；与 10 周时间表冲突。
- **所需资源**：4–8 GPU 周；2 名工程师；2TB 存储；WMA-0 权重。
- **落地步骤**：小规模 pilot（1 任务）→ 生成数据 → 训练 → 真机 A/B；不过门就剪枝。
- **风险**：幻觉；物理不一致；sim-to-real gap；计算；时间。
- **通过门**：生成数据在单任务通道 +5pp；否则剪枝。

### 7.9 M8 · DUAL-ARM AUX（观察）

- **动机**：32 任务含双手协调；新数据有 `Two_Robot_Clean_Table_Left/Right`、`DualRobot_Clean_Table`；可学角色分配/避碰。
- **与现有方案的差异**：把多机器人数据当辅助任务，不加载第二个模型；用同一 VLA 的语言/角色标签学习协调；不是多智能体策略。
- **技术可行性**：中。数据量有限（200–300 eps/任务）；多机器人 vs 双臂有 gap；仿真可补。
- **所需资源**：1 GPU 周；1 名工程师；仿真。
- **落地步骤**：数据分析 → 辅助任务微调 → 双臂任务 A/B。
- **风险**：数据不足；任务不匹配；负迁移。
- **通过门**：双臂任务 +5pp；其他任务不回归。

## 8. 风险与合规

### 8.1 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 场景标签/物体位姿只离线生成；线上只有 VLA + 记忆 | 最低 | 保守首选 |
| C2 确定性控制器 | 记忆/路由/重排/伺服无学习权重；VLA 唯一 | 低；需向官方说明 | 主推 |
| C3 同 checkpoint 特征 | 描述子用同一 VLA encoder，不加载第二个模型 | 低–中；需说明 | 需要强描述子时用 |

**禁止**：在线加载第二个学习策略、残差网络、独立视觉编码器、GNN 门控、Grounded SAM、CLIP。离线可以用工具做标注，但不进入提交包。提交材料写清楚：记忆是数据库，重排是确定性评分，伺服是控制律。

### 8.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 检索 mismatch | 选错轨迹 | 任务/相位硬过滤；几何优先；置信度低回退 VLA |
| 物体位姿误差 | 对齐偏 | 双目 + ICP；透明/反光回退腕部 2D；每机器人重标定 |
| DTW/检索延迟 | p99 超 | 近似检索；预计算；K≤8；每 30 步查一次 |
| 记忆规模 | 内存/加载 | 关键帧 stride；分层索引；只读 mmap；按任务分片 |
| 候选多样性不足 | 重排无效 | 多采样/温度；测试时增强；必要时加噪声 |
| 单模型解释 | 被判第二个模型 | C1/C2/C3；提交材料；不加载第二个学习模型 |
| 未见物品 | 记忆无相似轨迹 | VLA 语义主导；记忆只重排；辅助任务 M3 |
| 背景归一化过度 | 去掉有用线索 | 只归一化色度；保留亮度/阴影；可开关 |
| 人为干扰误报 | 频繁停 | 动作条件残差 + 连续 K 帧 + 置信度 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B；bootstrap；320 trials SE≈2.4pp |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组；排除同 episode |
| `pivot` 语义不一致 | 动作被拒/机器人不动 | 先用 `example_env.py`/单任务通道验证；零 pivot 回退 |
| 提交次数限制 | 无法多次 A/B | 邮件确认；单任务通道先验证；一次提交则保守 |
| 60 辅助任务重叠 | 负迁移/泄漏 | 数据指纹/去重；相似任务降权 |
