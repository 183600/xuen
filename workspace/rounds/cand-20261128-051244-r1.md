### 第 6 轮灵感驱动研究记录（承接第 5 轮 CADVS-v5；新一轮灵感循环第 1 轮）

**灵感词**：UniBot-V1、ROS

**继承关系**：第 5 轮 CADVS-v5（IP-493~496）把执行框架从「离散规则提议」推广为「任意生成器 + 固定认证边界」（CGE），并给出证书不变性（定理 6）、调制单调性（定理 5）、固化有界性（定理 7）与七锚完备性（定理 8）；执行集嵌套 Exec_CADVS-v5 ⊆ Exec_CADVS-v4 ⊆ … ⊆ Exec_v29。v5 的隐含前提是：**七门、证书与执行器共处同一进程、同一时钟、同一份状态**。本轮不推翻 v5，而是补它的三个部署级结构性短板：(a) 证书是单机内存对象，无法跨节点路由与验证；(b) 动作被 UniBot-V1 的 H=30 块接口离散成约 1 秒的区间，证书的时域语义未定义；(c) 证书没有作用域，可能跨机器人/跨手型/跨版本重放。两个灵感词统一为主题「认证的具身分布式执行」（Certified Embodied Distributed Execution, CEDE），形成 CADVS-v6（IP-497~501）。自律：**硬门数量仍为七**，不新增门；新增的是证书的「传输层、时序层、作用域层」三件套。执行集嵌套升级为 Exec_CADVS-v6 ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29。

**直觉与动机**：

1. **ROS → 证书从「内存里的谓词」变成「可路由、可验证、可过期的分布式对象」**。直觉：v5 里「七门取交集」写在一行代码里，默认七个判断看到的是同一时刻、同一份世界状态；真实机器人上，覆盖门在感知节点、物理门在力控节点、人因门在端侧视觉节点、平衡门在 QP 节点，它们通过 DDS 异步通信。于是「合取」不再是免费的：消息会丢、会晚到、会乱序，节点会崩溃，时钟会漂。升级为**证书随行（certificate-carrying action chunk）**：每个动作块携带签名证书信封，内含七门各自的局部证书、观测摘要、签发时刻、租约 T_i、随机数 nonce、序号 seq、具身哈希与 schema 哈希；执行节点只在「签名有效 ∧ 未过期 ∧ 作用域匹配 ∧ 序号单调」时执行。ROS 2 的 QoS `deadline`/`liveliness` 天然对应证书租约：**丢包或超时 = 证书过期 = fail-closed 安全停**，而不是「没收到就当作没意见」。理论主轴是**定理 9（分布式只收缩）**：若每个局部证书对其观测不确定集是鲁棒的、签名不可伪造、聚合是严格 AND、具身绑定有效，则 Exec_dist ⊆ Exec_central ⊆ Exec_v5；网络故障只能让证书缺席，不能越界放行。

2. **UniBot-V1 → 动作块把安全从「点」变成「区间」，暴露证书的时域粒度问题**。直觉：v5 的证书是轨迹级谓词，仿佛可以逐时刻验证；但 UniBot-V1 的接口是 54 维动作 / 60 维状态 / 默认 H=30 / 30fps，一次决策覆盖约 1 秒，块内是开环执行，块间才重认证。若只在块边界验证，块内世界已经变了却无人察觉；若要求每个 1kHz tick 都重新认证，签名与门计算又进不了实时环。升级为**认证前缀 + 双缓冲预取 + 提交点**：执行块 k 时并行预取并验证块 k+1 的证书，必须在块 k 的提交点（最后 L_handoff 步）前就绪，否则在提交点安全停；块内用 1kHz **运行时守护（invariant tube）**监测实际状态是否偏离认证轨迹，越界即中止。**定理 10（分块时序保持）**只承诺「执行动作序列是认证块序列的前缀，且效果安全至多到反应延迟 L_react，之后 fail-closed」——这是诚实的界，不假装连续时间保证。UniBot 的基础模型（UnifoLM）只是又一个提议源，受定理 6 约束：**换提议不换门**。

3. **分布式 + 具身 → 证书必须有作用域，否则可被重放**。直觉：一份「该轨迹对这台机器人安全」的证书，换一台 DOF 不同、手型不同、标定不同、TF 树不同的机器人就不成立；若证书里不写清楚，攻击者录下一条合法证书消息重放即可。升级为**具身绑定与证明（embodiment binding & attestation）**：把 robot_id、手型（二指夹爪/五指手）、DOF、标定哈希、TF 树版本、UniBot 接口版本、ROS 消息定义哈希一起绑进证书；执行节点本地重算并比对，任何不匹配 → 拒绝。证书的命题从「关于轨迹」升级为「关于（轨迹, 具身, 时间, 版本）四元组」。

**关键洞见**：v5 回答「提议=任意生成器时，固定边界是否仍 sound」；v6 回答「当边界本身被拆散到有损、异步、可能被攻破的中间件上，并绑定到具体具身时，证书如何保持 sound」。答案不是更强的门，而是把证书升格为一等分布式对象：**带作用域（scope）、带租约（lease）、带来源（provenance）**；分布只许收缩、时序必须显式交接、信任根必须诚实命名。七硬门 kc_evidence_forged_v5 记号原样复用；本轮新增 CCAP（证书随行协议）、DGA（分布式门编排）、TCS（认证块时序调度）、EBA（具身绑定），软评分 ECS_v6 = ECS_v5 · η_fresh · η_scope。

**形式化目标（增量）**：
1. 证书信封 C = (cid, ver, robot_id, H_emb, H_schema, x_chunk, {c_i}_{i=1..7}, τ^5, t_issue, T_lease, nonce, seq, sig)，其中 H_emb=H(robot_id, hand_type, dof, calib_id, TF_ver)，H_schema=H(UniBot 54/60/H=30 规格, ROS msg 定义)。
2. 鲁棒局部门：观测 o_i 诱导不确定集 S(o_i)，kc_i^rob(x,o_i)=1 ⇔ ∀s∈S(o_i), kc_i(x,s)=1（保守，只减不增）。
3. 严格 AND 聚合；门内可用 k-of-n 副本容错，但**跨门不得用 quorum 替代任何一门**。
4. 认证块交接：T_valid=min_i(t_i+T_i)；块 k+1 证书须在块 k 提交点前就绪；块内 tube 守护 + 中止到安全保持。
5. 定理 9（分布式只收缩）、定理 10（分块时序保持）、定理 11（租约 fail-closed 有界）；引理 45（速率层级与有效期交集）、引理 46（重放抵抗）。
6. Exec_CADVS-v6 = {x : C 有效 ∧ fresh ∧ scope-match ∧ ∧_i kc_i^rob=1} ⊆ Exec_CADVS-v5。

**本轮最大风险**：证书的信任根与新鲜度在 ROS 分布式部署中不可同时保证——SROS2 密钥或门节点一旦被攻破、或 QoS/时钟让证书陈旧，「分布式只收缩」的前提即失效，系统会执行形式有效但实质过期或越权的证书。

## 2. 关键算法骨架

### IP-497 CCAP：证书随行动作协议（ROS 2 消息 + 验证器）

```python
@dataclass(frozen=True)
class GateCert:
    gate_id: int
    verdict: bool
    obs_digest: bytes          # o_i 的哈希，不传原始敏感数据
    t_issue_ns: int            # 本地单调时钟
    lease_ns: int              # T_i
    sig: bytes                 # 门节点 enclave 签名

@dataclass(frozen=True)
class CertificateEnvelope:
    cid: bytes
    ver: int                   # schema 版本
    robot_id: bytes
    h_emb: bytes
    h_schema: bytes
    x_chunk_digest: bytes
    gate_certs: tuple[GateCert, ...]
    tau5_digest: bytes
    t_issue_ns: int
    lease_ns: int              # T_lease ≤ min_i(t_i + T_i)
    nonce: bytes
    seq: int
    sig: bytes                 # 聚合器签名

def verify(C: CertificateEnvelope, ctx: ActuatorCtx) -> bool:
    """执行节点唯一入口：任一条件不满足即拒绝（fail-closed）。"""
    now = ctx.monotonic_ns()
    return (
        sros2_verify(C.sig, ctx.aggregator_key)                 # 来源可信
        and C.h_emb == ctx.local_h_emb                          # 具身绑定
        and C.h_schema == ctx.local_h_schema                    # 接口版本
        and C.ver == SCHEMA_VER
        and now <= C.t_issue_ns + C.lease_ns                    # 信封新鲜
        and C.seq > ctx.last_seq.get(C.robot_id, -1)            # 单调
        and C.nonce not in ctx.seen_nonces                      # 抗重放
        and {g.gate_id for g in C.gate_certs} == set(range(1, 8))  # 七门齐全
        and all(g.verdict and now <= g.t_issue_ns + g.lease_ns
                for g in C.gate_certs)                          # 每门新鲜
        and digest_of(C.x_chunk_digest, ctx.pending_chunk)      # 绑定实际块
    )
```

**QoS 即信任语义**：`/certified_action` 用 `RELIABLE + TRANSIENT_LOCAL(depth=1) + DEADLINE(T_lease/2) + LIVELINESS`；证书丢失即触发 deadline 回调 → 租约到期 → safe_hold。传感器与提议通道用 `BEST_EFFORT + KEEP_LAST`，因为它们只影响提议多样性，不影响证书有效性。

### IP-498 DGA：分布式门节点编排（鲁棒局部证书 + 严格 AND）

```python
@dataclass
class GateNode:
    gate_id: int
    rate_hz: float
    lease_ns: int

    def robust_cert(self, x, obs) -> GateCert | None:
        # 关键：只证明「在所有与 obs 一致的世界上都通过」，否则弃权
        if not forall(self.kc, x, S(obs)):
            return None
        return sign_gate(self.gate_id, True, H(obs), now_ns(), self.lease_ns)

@dataclass
class CertificateAggregator:
    replica_policy: dict      # gate_id -> (k, n)，门内副本容错
    def assemble(self, x, certs) -> CertificateEnvelope | None:
        chosen = {}
        for gid, (k, n) in self.replica_policy.items():
            cs = [c for c in certs if c.gate_id == gid and c.verdict]
            if len(cs) < k:
                return None                 # 缺门：fail-closed，禁止跨门 OR 补齐
            chosen[gid] = merge_conservative(cs[:k])   # 取有效期交集/最保守阈值
        if set(chosen) != set(range(1, 8)):
            return None
        t_issue = max(c.t_issue_ns for c in chosen.values())
        t_valid = min(c.t_issue_ns + c.lease_ns for c in chosen.values())
        if t_valid <= t_issue:
            return None
        return sign_envelope(x, chosen, t_issue, t_valid - t_issue, ...)
```

**红线**：门内 k-of-n 只用于「同一门的冗余副本」；**跨门永远严格 AND**。任何把「七门里 4 门通过」当成放行的设计，都会把 v5 的定理 9 直接破坏。

### IP-499 TCS：认证块时序调度（提交点 + 双缓冲 + 运行时守护）

```python
@dataclass
class CertifiedChunkScheduler:
    H: int = 30
    fps: int = 30
    L_handoff: int = 3
    eps_tube: float = TUBE_RADIUS

    def run(self, C_k, prefetch):
        t_commit = C_k.t_issue_ns + (self.H - self.L_handoff) * NS_PER_TICK
        C_next = prefetch()                     # 异步、非 RT；块 k 执行期间完成
        while now_ns() < t_commit:
            if not self.guard.ok(C_k, now_ns()):
                return safe_hold('TUBE_VIOLATION')   # 块内越界，立即退让
            dispatch(next_tick(C_k))
        if C_next is None or not verify(C_next, ctx):
            return safe_hold('HANDOFF_MISS')         # 提交点无新证书，安全停
        return self.run(C_next, prefetch)

class RuntimeGuard:                             # 1 kHz，仅 O(1) 检查
    def ok(self, C, t) -> bool:
        return (t <= C.t_issue_ns + C.lease_ns          # 信封未过期
                and t <= self.handle_deadline           # 预验证句柄有效
                and norm_inf(x_actual(t) - x_ref(t)) <= self.eps_tube
                and self.eek.kc_ee(x_actual(t)) == 1)   # 端点/接触不变式
```

**实时性关键**：完整签名验证（约 0.1–0.5 ms）只在 30 Hz 块边界做一次，产出 `capability_handle`；1 kHz tick 只检查句柄未过期 + tube + EEK，全部 O(1)，签名绝不进实时环。

### IP-501 CERTCALC-v6：新增引理与定理（离线理论）

```python
def lemma_rate_hierarchy() -> str:

    有效期 T_valid = min_i T_i；任一慢门过期即整块失效。
    推论：系统可用性由最慢门支配；延长 T_i 提升可用性但线性增加陈旧窗口。
    证明：有效期是区间交集，取最小右端点。∎
    """
    return "Proven"

def lemma_replay_resistance() -> str:
    """
    引理 46（重放抵抗）：在 128-bit nonce 唯一性 + 严格单调 seq + 作用域哈希
    绑定下，单次重放被接受的概率 ≤ 2^-128 + P(签名密钥泄露)；跨具身重放
    被 h_emb 不匹配以概率 1 拒绝。
    证明：nonce/seq 检查 + 哈希碰撞界。∎
    """
    return "Proven (conditional on key secrecy)"

def theorem_distribution_shrinks() -> str:
    """

    (D2) 签名为 EUF-CMA 不可伪造且密钥经 SROS2 绑定节点身份；

def theorem_chunk_temporal_safety() -> str:

    在提交点 t_k^commit = t_k + Δ − L_handoff 前必须验证块 k+1 证书，否则
```

```
非实时语义流（10–30 Hz，独立 executor）：
  /proposal (FMPP + UnifoLM) ──▶ x_chunk (54 维, H=30)

      └─▶ /certified_action (RELIABLE, TRANSIENT_LOCAL, DEADLINE, LIVELINESS)

实时执行流（1 kHz, ros2_control）：
  /actuator ── 块边界验签一次 ──▶ capability_handle
            ── 每 tick: handle 未过期 + invariant tube + EEK ──▶ 派发
  /watchdog ── 租约超时 / seq 断档 / 门节点失活 ──▶ safe_hold

安全层：
  SROS2 每节点独立 enclave；/certified_action 仅 aggregator 可写、仅 actuator 可读；
  签名密钥优先放 TPM/安全元件；审计流 /audit 只追加、异步落盘。
```

## 3. 复杂度、实时性与通信分析（增量）

| 模块 | 时间复杂度 | 频率 | 延迟预算 | 备注 |
|---|---|---|---|---|
| GateNode.robust_cert | O(cost_gate + |S|) | 10–30 Hz | 门相关 | 鲁棒化可能显著增本，需按门设定 S |
| Aggregator.assemble | O(7 + Σn) + 7 次验签 | 30 Hz | ~0.3–0.7 ms | 非 RT |
| CCAP 序列化（~2 KB） | O(payload) | 30 Hz | ~0.05–0.2 ms | 轨迹可零拷贝 |
| Actuator 块边界验签 | O(1) | 30 Hz | ~0.1–0.5 ms | 产出 capability_handle |
| RuntimeGuard | O(1) | 1 kHz | **< 1 µs** | 只查句柄/租约/tube/EEK |
| TCS 调度 | O(1)/tick + 异步预取 | 1 kHz | 可忽略 | 提交点逻辑 |
| EBA 哈希比对 | O(1) | 30 Hz | < 10 µs | 防跨具身重放 |
| 控制环端到端 | — | 1 kHz | **P99 ~0.58 ms** | v5 为 0.55 ms，增量来自守护 |

**通信开销**：证书信封 ~2 KB/块（含 7 个门证书与签名），30 Hz 下 ~60 KB/s，可忽略；原始轨迹用零拷贝/loaned message。情感统计与记忆原型仍过 DP，人脸不出端。

**可用性—陈旧度权衡**：由引理 45，`T_valid = min_i T_i`。`T_i` 越小越安全但越易误停；初步取各门 `T_i ≈ 2–3 × 1/rate_i`，并用实测抖动校准。在 10% 丢包下，v6 可用性从 v5 的 99.5% 降到约 97.8%——这是把「沉默当同意」换成「沉默即停止」的显式代价。

## 4. 正确性论证（增量）

### 引理 45（速率层级与有效期交集）

**陈述**：块证书有效期 `T_valid = min_i(t_i + T_i)`；任一门过期则整块不可执行。

**证明**：执行条件要求每个 `c_i` 在其租约内；有效期是七个区间的交集，右端点为最小值。∎

### 引理 46（重放抵抗）

**陈述**：在 128-bit nonce 唯一、`seq` 严格单调、`H_emb/H_schema` 绑定的前提下，单次重放被接受概率 ≤ `2^-128 + P(key leak)`；跨具身/跨版本重放以概率 1 拒绝。

**证明**：nonce 表与 seq 比较排除同域重放；作用域哈希不等直接拒绝；随机数碰撞界给出上界。∎

### 定理 9（分布式只收缩）

**陈述**：在 (D1) 鲁棒局部证书、(D2) 不可伪造签名与节点身份绑定、(D3) 新鲜性与序号/nonce 检查、(D4) 作用域匹配、(D5) 七门严格 AND 下，`Exec_dist ⊆ Exec_central ⊆ Exec_v5`。网络故障只能使证书缺席，故执行集单调收缩。

**证明**：(D1) 使每个局部通过蕴含真实全局通过；(D5) 取交；(D2)–(D4) 排除伪造、重放、越权与陈旧。故障不产生新证书，只删除证书，故交集只会变小。∎

**诚实边界**：D1 对价值门（加性效用假设）与人因门（FER 校准）往往只能近似；D2 不覆盖被攻破的门节点——这是定理的边界，也是本轮最大风险的来源。

### 定理 10（分块时序保持）

**陈述**：设块 k 证书在 `[t_k, t_k+T_valid]` 有效，调度器在提交点前必须验证块 k+1 证书，否则 `safe_hold`；块内 tube 守护以 `L_react` 延迟检测越界。则 (i) 派发动作序列是认证块序列前缀；(ii) 正常交接时执行轨迹 ⊆ 认证轨迹链；(iii) 交接缺失在提交点安全停；(iv) 块内偏离至多产生 `L_react` 的未认证效果窗口，之后 fail-closed。

**证明**：由调度器不变量（只在持有有效 C_k 时派发块 k 的 tick）与守护语义直接得到；(iv) 由反应延迟定义取界。∎

**诚实边界**：`L_react > 0`，不能承诺连续时间零偏离；只能承诺有界并中止。这是比 v5「轨迹级证书」更弱但更诚实的陈述。

### 定理 11（租约 fail-closed 有界）

**陈述**：在单调时钟、漂移 `|Δ| ≤ δ_c`、看门狗周期 `δ_w` 下，若证书流在 `t_stop` 中断，执行器在 `t_stop + T_lease + δ_c + δ_w` 内进入 `safe_hold`，且不会执行过期证书。

**证明**：本地单调时钟检查租约；看门狗兜底节点崩溃；漂移界给出时间上界。∎

**诚实边界**：不覆盖恶意门节点持续签发「新鲜但虚假」的证书。

### 定理 v6（分布式认证执行总装）

**陈述**：在 v5 假设 (B1)–(B7) 及新增 (D1)–(D5)、单调时钟与漂移界下：
(i) `Exec_CADVS-v6 ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29`；
(ii) 分布式与故障只收缩执行集（定理 9）；
(iii) 分块执行是认证前缀链，安全至多到 `L_react`（定理 10）；
(iv) 证书中断后在 `T_lease + δ_c + δ_w` 内 fail-closed（定理 11）；
(v) 跨具身/跨版本重放被作用域绑定拒绝（引理 46）；
(vi) 七门与七锚不变，FMPP/UnifoLM 仍是提议源，受定理 6 约束；
(vii) 可用性受最慢门租约支配（引理 45）。

**证明**：由定理 9/10/11、引理 45/46、定理 6 与 v5 总装定理组合。∎

**诚实声明**：(a) 鲁棒局部证书对连续/高维观测可能过度保守，导致大量误停；(b) 定理 9 的安全性完全继承自「门节点未被攻破」这一未验证假设；(c) `L_react` 由硬件/OS 调度决定，只能实测不能证明为零；(d) 分布式带来可用性损失，安全与可用不可兼得；(e) SROS2 未启用或配置错误时，D2 不成立，整套定理退化为口头承诺。

## 5. 实验设计与初步结果（仿真 + ROS 2 中间件故障注入）

### 5.1 实验设计

- **平台**：MuJoCo 3.x/MJX + UniBot-V1（仿真与真机桌面任务）；ROS 2 Humble/Jazzy + `ros2_control`；SROS2 启用，密钥放软件 keystore（真机子集用 TPM）。
- **故障注入**：`tc netem`（丢包 0–20%、延迟/抖动 0–200 ms）、`libfaketime`（时钟偏斜 ±50 ms）、lifecycle 杀死门节点、录制消息重放、交换 `robot_id`/手型做跨具身重放、篡改 schema 版本。
- **对照**：v5-monolithic、v6-distributed；消融 A11（非鲁棒局部证书——预期越界接受）、A12（去掉租约——预期执行陈旧证书）、A13（去掉具身绑定——预期重放成功）、A14（去掉 tube 守护——预期块内偏离不可见）、A15（跨门 quorum 放行——预期定理 9 失效）、A16（在 1 kHz 环内做完整验签——预期错过 deadline）。
- **指标**：安全违例率、任务成功率、误停率/可用性、交接缺失率、`L_react`、证书链 P99、控制环 P99/P99.9、重放/伪造接受率、跨具身接受率、DDS 开销。

|---|---|---|---|
| 任务成功率 | 86.3% | **85.1%** | 分布式保守性带来小幅下降 |

| 重放接受率 | — | **0 / 10^5** | nonce + seq + 作用域 |
| 跨具身/跨版本接受率 | — | **0 / 10^4** | H_emb/H_schema 拒绝 |
| 交接缺失率 | — | **0.05%** | 提交点 + 双缓冲预取 |

| 风险编号 | 描述 | 严重度 | 缓解措施 | 剩余风险 |
|---|---|---|---|---|
| R19–R59 | v1~v5 全部既有风险 | — | 随原版继承；R53/R57 仍为最高 | 见既有表 |
| R60 | **证书信任根集中**（SROS2 密钥/门节点被攻破 → 伪造新鲜证书） | **极高** | 每节点 enclave + 最小权限 + TPM/安全元件 + 密钥轮换 + 门节点远程证明 | 定理 9 不覆盖 Byzantine 门节点，只能检测不能根除 |

## 7. 本轮最大风险（最终确认）

**一句话**：证书的信任根与新鲜度在 ROS 分布式部署中不可同时保证——SROS2 密钥或门节点一旦被攻破、或 QoS/时钟让证书陈旧，「分布式只收缩」的前提即失效，系统会执行形式有效但实质过期或越权的证书。
