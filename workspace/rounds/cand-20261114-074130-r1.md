# 第 70 轮（承接第 69 轮「FLUID-RAS」IP-253~263；本轮灵感：「状态隔离」×「交互设计」）

> R69 让系统学会了「问」，却漏掉一个架构事实：**回答不是知识，回答是一份来自外部的写请求**。R69 的 `update_belief(modes, answer)` 把这份写请求直接落到驱动控制的信念上；「k 个正交证据源一致」只是提高了写的门槛，并没有改变「一旦写成就生效」的单阶段语义。于是一旦回答被投毒、过期、重放，或流模型幻觉出一个幻影模态，污染就沿 `answer → belief → λ → actuator` 直达执行器。R69 自陈的「问错比不问更危险」，本质是**写路径没有隔离**。
>
> 本轮两个灵感正好补上互补的两半：
> - **状态隔离**：把「交互产生的临时知识」关进隔离区 Q，把「已认证的控制状态」放在 C；Q 不能直接写 C，只能通过一次**带证据的提升（promotion）**以事务方式提交，且可回滚。隔离不只是逻辑分区，还要有污点、来源、版本、TTL 与泄漏监测。
> - **交互设计**：把「随便问」改成**交互契约**——只问能改变决策的最小判别问题，允许弃权与纠正，声明理由与后果，优先可交叉验证的证据；交互的动作、节奏与披露范围本身就是安全接口。
>
> 核心命题：**在「问」与「信」之间加一道交互气闸：未提升的交互内容对控制状态零影响；提升必须是一次可审计、可回滚、带污点证明的事务；交互本身按契约设计，使「问错」最多浪费预算，而不能改写安全。** 命名 **AIRLOCK-RAS**（Attributed, Isolated, Rollbackable, Least-privilege, Contracted Knowledge）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**求证的结果允许落在哪里、以什么方式生效**」——不是所有答案都配得上直接改写控制器。

## 0. 直觉与动机

**灵感 1（状态隔离 → 把「访客的话」和「飞行控制律」分开）**
直觉：在安全关键系统里，访客可以递纸条，但纸条不能直接写进控制律。R69 的系统会「问」，却把所有回答都当作可以直接改写的内部信念；这相当于把交互区、任务区与安全区放在同一块可写内存里。状态隔离要求**能力分离**：只有控制状态 C 拥有执行器权限；世界/任务状态 W 可以预测但不能直接驱动执行器；交互状态 Q 只能写入隔离区；审计日志 L 只可追加。更关键的是**信息流隔离**：每个状态单元携带来源与污点，派生信念继承最不可信祖先的污点；合并可信数据不能自动「洗白」一条未经验证的回答。隔离还有横向维度：每次交互是一个带 nonce 与 TTL 的会话胶囊，一个被投毒的会话不能污染另一个会话。

**灵感 2（交互设计 → 问句不是文案，是协议状态机）**
直觉：R69 把注视、探针、问句塞进动作空间，解决了「可以问」，但没有解决「怎样问才不制造新的风险」。交互设计给出的不是界面美化，而是**协议约束**：只问「答案会改变决策」的最小判别问题；答案 schema 里永远允许 `unknown`、`refuse`、`correct`；系统必须说明为什么问、有哪些选项、回答会改变什么、隐私范围多大；不得用诱导性措辞；高影响提交需要第二把钥匙。这样的契约同时降低社交工程、交互疲劳与隐私泄漏，也让信息动作在物理上更容易被认证。

**灵感 3（两个门 → R69 的 MCG 管「信不信自己」，本轮 PSG 管「让不让别人改自己」）**
直觉：R69 的模态校准门 MCG 问的是「我对自身模态分布的置信准不准」；但即使 MCG 通过，外部回答仍然可能是谎言。AIRLOCK 增加第二个门 PSG（Promotion & declassification Gate）：它检查契约有效性、证据正交性、污点等级、物理一致性与提交风险。两个门相互独立：MCG 失败时禁用 VoI 决策；PSG 失败时交互结果留在 Q、控制退回 R68 保守。两门同时失败才是彻底退化。把「自省」与「他信」分开，是状态隔离在认知层的直接体现。

**灵感 4（严格包含 → R69 是「立即提交」边界，R68 是「永不提交」边界）**
直觉：AIRLOCK 不推翻 R69，而是把 R69 的「k 源一致后直接写信念」重述为一种最宽松的提升策略：若 PSG 对每个满足 k 源一致的补丁立即放行且 TTL 为无穷，则控制路径与 FLUID-RAS 逐指令一致；若 PSG 永远拒绝，则与 R68 的纯保守一致。于是 AIRLOCK 是夹在两者之间的**连续谱**：隔离强度就是提交策略的严格度。安全侧可以严格不弱于 R69，效率侧保留 resolution bonus。

**灵感 5（攻击面转移 → 从「回答是否撒谎」转向「写路径是否可信」）**
直觉：R69 的威胁模型集中在「人会说谎、模型会幻觉」。状态隔离把问题推进一层：即使回答是诚实的，写路径也可能被**重放、过期、跨会话串扰、污点洗白、共享编码器侧信道**攻击。交互设计则把「问什么、怎么问、问到什么程度」纳入攻击面。新的威胁模型必须覆盖写路径与协议本身，否则隔离只是把毒药从一个杯子倒进另一个杯子。

## 1. 形式化定义（增量：定义 310–326）

**定义 310（AIRLOCK-RAS 总览）** AIRLOCK-RAS = (SPL, TAI, ICG, QBS, PSG, TBC, SIM, LIP, SML, RAS-WM†)。五条不变式：
(i) **执行器权限唯一**：只有控制状态 C 能签发执行器指令；W、Q、L 均无执行能力；
(ii) **写隔离**：Q → C 不存在直接写边，唯一通道是 PSG 签发的提升证书 + TBC 事务；
(iii) **信息流**：每个状态单元携带来源与污点，派生状态继承污点；显式降密只能经 PSG；
(iv) **证据与预算纪律**：继承 R69 定义 293 的 k 源一致、交互频率/位移/成本硬约束；
(v) **零在线学习写操作**：学习只发生在影子模型 S，提升到 C/W 需维护期证书（继承 R68 定义 276-i）。

**定义 311（状态分区与能力）** 四个分区：
- C ∈ 𝒞：认证控制状态，含 λ、认证前缀长度 k、安全包络、已认证模态后验、标定状态；
- W ∈ 𝒲：任务/世界模型状态，含 z_t、FMP 采样、模态分解、FMA 分数、WM 预测；
- Q ∈ 𝒬：交互隔离区，含会话胶囊、回答、候选信念补丁与污点；
- L：只追加来源账本（Merkle 哈希链）。
能力集：Cap(C) = {read, write, actuate}；Cap(W) = {read, write-by-estimator}；Cap(Q) = {read, write-by-interaction}；Cap(L) = {append, read}。任何请求若需要 `actuate` 或 `write(C)` 而当前分区不是 C/PSG/TBC，直接拒绝并记入 L。

**定义 312（会话胶囊）** Q = ⨁_s Q_s。每个会话 s 有 nonce、主体身份、契约 id、起始/到期时间、信任层级与最大披露范围。会话之间无直接读边；跨会话合并只能经 L 与 PSG，并且需要独立证据。隔离原则：**宁可不合并，不可错合并**。

**定义 313（来源与污点格）** 来源 p = (source_id, channel, session_id, time, contract_id, trust_class)。信任类构成格 T0 ≺ T1 ≺ T2 ≺ T3 ≺ T⊥（越后越不可信）：
- T0：独立物理证据或 C-RAS-WM 认证；
- T1：模型内部（流采样、WM 预测）；
- T2：多源独立人类证据且已验证；
- T3：单源未验证回答；
- T⊥：已撤销/疑似投毒。
派生状态的污点 `t(x) = ⊔_{s∈src(x)} t(s)`，其中 ⊔ 取格上界（更不可信者）。**降密** `t → t'`（t' 更可信）只能由 PSG 用证明 π 显式执行；重复同一来源不提升信任，混入可信数据也不降低污点。

**定义 314（交互契约 IC）** IC = (id, target, q_family, answer_schema, verify_set, k_min, budget, timeout, expiry, commit_rule, rollback_policy, disclosure, consent, abort)。其中：
- target 是要区分的模态对/决策边界；
- q_family 是**最小判别问句族**（只允许能改变 target 后验的问题，不含开放式劝诱）；
- answer_schema 至少包含 `{option, confidence, unknown, refuse, correct}`；
- verify_set 是与回答源正交的验证通道；
- commit_rule ∈ {immediate, probation, two_key}；
- disclosure 必须声明「为何问、选项、回答改变什么、隐私范围」。
契约是交互的类型系统：schema 之外的回答不能进入候选补丁。

**定义 315（隔离信念 Q）** 会话 s 在 Q 中维护替代后验 q_s(M) 与证据表 {(value, taint, provenance)}。交互产生候选补丁 δQ = (target, likelihood, taint, contract_id, nonce)；δQ 只是**请求**，不是对 C 的写。Q 可以被过期、冻结或整体清除而不影响 C 的合法性。

**定义 316（提升门 PSG）** PSG(δQ, C, L) → cert 或 reject。检查：
(a) 契约有效、未过期、nonce 与会话匹配；
(b) target 已识别且回答在 schema 内；
(c) 降密后污点不高于阈值 τ_taint；
(d) 至少 k_min 个正交证据源一致（R69 定义 293-iii），且验证源不包含回答源本身；
(e) 与 C 的认证物理不变量、安全包络、标定常数一致；
(f) 提交的期望认证风险不高于拒绝的期望风险（保守比较）；
(g) 影响有界：补丁只能修改认知量（模态后验、λ 的 resolution bonus），不得修改安全包络、认证阈值、传感器标定常数；
(h) 证书写入 L，包含补丁哈希、逆补丁哈希、证据哈希、C 版本、污点、到期时间与签名。
`cert = (target, patch_hash, inverse_hash, evidence_hash, c_version, taint, expiry, nonce, sig)`。

**定义 317（控制非干扰）** 固定认证观测流 o_{0:t} 与提交序列 cert_{0:t}，控制状态更新满足
`C_{t+1} = F_C(C_t, cert_t, o_t)`，
且与 Q_t 中**未提升内容**无关。Q 的内容可以经由 ICG 影响「问哪个经认证的信息动作」，从而改变观测流；但这部分影响等价于一次受 R69 定义 302 约束的信息动作，风险 ≤ ε_int，**不构成对 C 的未认证写**。这是本轮安全论证的边界：非干扰保护的是控制状态，不是世界状态。

**定义 318（污点感知 VoI）** 对契约内信息动作 g ∈ IC：
`VoI_IC(g) = κ(t_answer) · [H(M|C) − E_{y~p(·|g,C)}H(M|C,y)] − c(g) − c_verify(g)`，
其中 κ(t) ∈ [0,1] 随污点升高而下降。若 `VoI_IC ≤ 0` 则不问。这样「问了也验证不了」的问题在信息论上就不值钱，交互设计直接进入决策函数，而不是事后补丁。

**定义 319（事务提交与回滚）** TBC 提供 prepare / commit / abort / revoke：
- prepare：冻结 C 版本 v，计算补丁 δ 与逆补丁 δ^{-1}，检查前置条件；
- commit：原子地 `C_{v+1} = δ(C_v)`，L 追加事务；
- abort：丢弃 δ，C 不变；
- revoke：若后续证据与已提交信念矛盾，沿提交 DAG 逆序应用 δ^{-1}；若级联失败或依赖不可逆，强制回退 R68 保守并清除相关 Q。
回滚只承诺**未来控制**的认知恢复；已经执行的物理信息动作不可撤销，但受 ε_int 约束。

**定义 320（显式降密）** Q → C 的信任提升只能通过证明 π = (k 个正交源、一致性检验、时效、必要时人工双钥匙、来源独立性说明)。禁止隐式降密：聚合、平均、重复询问同一来源都不降低污点。这是「污点不可洗白」的机制化。

**定义 321（影子反事实与学习隔离）** 反事实 rollout 与学习更新在影子副本 S（C/W 的 copy-on-write 快照）中执行；在线环路对 C/W 零学习写。影子模型的提升只在维护窗口，经与 PSG 同构的证书与回归门禁。隔离不等于不学习：学习发生在隔离区，生效是另一件事。

**定义 322（可理解交互协议 LIP）** 每条交互消息必须包含四元组 `(why, options, consequence, privacy)`，并允许 `unknown/refuse/correct`。附加约束：选项平衡、非诱导、不制造时间压力、尊重轮次与打扰预算、在人类不适或风险升高时可 abort。交互设计被形式化为协议状态机，而不是自然语言风格建议。

**定义 323（隔离监测 SIM）** 持续检查：非法 Q→C 边、污点洗白、跨会话读取、Q 过期、Q 与 C 后验发散、L 一致性、共享底座泄漏。共享底座泄漏用条件互信息估计：
`ε_leak = I(Q_content ; z_used_by_C | o_cert)`。
若 `ε_leak > τ_leak`，禁用共享条件编码、改用隔离 adapter，或冻结提交。报警动作：purge Q_s、冻结 PSG、回退 R68、写入 L。

**定义 324（威胁模型 ℰ_AIRLOCK）** `ℰ_AIRLOCK = ℰ_FLUID × ℰ_write`，其中 ℰ_write 包含：重放/过期回答、跨会话串扰、污点洗白、共谋欺骗、语言提示注入、共享编码器/时序侧信道、隐私推断、过度提问与交互疲劳、恶意弃权。R69 的 ℰ_FLUID 保留为「内容层」威胁，本轮新增「写路径层」威胁。

**定义 325（证书 J_AIRLOCK）** `J_AIRLOCK = (J_FLUID, state_version, partition_hash, taint_profile_hash, contract_id, commit_id, rollback_proof, isolation_audit, leak_estimate)`。Valid ⇔ Valid(J_FLUID) ∧ 无非法写边 ∧ 所有影响 C 的提交均有未过期证书 ∧ SIM 无报警 ∧ TTL 未被越过。

**定义 326（降级与活性）** 若 PSG 拒绝、SIM 报警、MCG 失败、TTL 到期或回滚级联失败：`λ = λ_floor(U_ale + U_epi)`，Q_s 冻结/清除，未提升内容不得进入 C，交互可临时禁用直到重新认证。活性要求：Q 的任何内容都不能无限期存活；过期即刷新或降级。隔离不能退化为永久瘫痪。

```python
    dQ = M.qbs.stage(ic, answer, provenance=...)

    # 3) 泄漏/陈旧/校准检查：任一失败即降级
    if M.sim.alarm() or M.sim.stale(dQ) or not M.mcg.ok():
        M.qbs.freeze(dQ); return control_step_R68(C, U_ale + U_epi)

    # 4) 提升门；拒绝时 U_epi 保持未消解
    cert = M.psg.promote(dQ, C, M.ledger, ic)
    if cert is None:
        M.qbs.expire(dQ); return control_step_R68(C, U_ale + U_epi)

    # 5) 事务提交；只有提交后 λ 才能获得 resolution bonus
    txn = M.tbc.prepare(C, cert)
    C2 = M.tbc.commit(txn, M.ledger)
    lam = max(M.efs.risk_scale(...), lam_floor(C2.U_ale))
    k = M.c_ras_wm.certified_prefix(M.ach.propose(x_prime, M.vista.H), ..., wm_preds)
    mode = select_mode(modes, C2.U_epi_after, lam)
    tau = M.pi_sigma.prefix_dispatch(mode.a[:k]) * lam

    # 6) 参与式审计、隔离监测与证书
    M.vqa_i.submit_async(g, answer, cert, txn)
    M.sim.check_after_commit(C2, M.ledger)
    return k, lam, mode, (C2.U_ale, C2.U_epi_after)
```

## 3. 推导

**引理 19（污点单调性与不可洗白）** 设状态 x 由来源集合 S 经任意可微/可组合运算派生，则 `t(x) = ⊔_{s∈S} t(s)`；任何聚合、平均、重复采样都不降低污点；只有 PSG 显式降密才能改变信任类。特别地，同一 T3 来源重复 100 次仍为 T3，混入 T0 数据后仍保留 T3 标记。证明：对派生树归纳；⊔ 单调，且信任类格的上界不因重复元素改变；降密是唯一改变信任类的操作。系：**「多数一致」只有在来源独立时才是证据，否则只是同一谎言的回声。**

**引理 20（回滚可靠性）** 若提交证书带有可逆补丁 δ^{-1}，且无后续提交依赖 δ，则 revoke 后 C 的所有认知分量回到提交前快照；λ 回到提交前的保守值，安全包络不因 revoke 扩大。若存在依赖，则按提交 DAG 逆序级联；级联失败时强制 R68 保守并清除相关 Q。物理信息动作不可撤销，但受 ε_int 约束，因此该引理只承诺未来控制的认知恢复。证明：由 TBC 的 prepare/commit 原子性与补丁只改认知量的约束直接得到。

**引理 21（契约约束的 VoI 与最坏伤害）** 令 𝒢 为全部候选信息动作，𝒢_IC ⊆ 𝒢 为契约允许的动作。则 `VoI_IC ≤ VoI`，即契约必然造成 VoI 折损；但在欺骗率 δ_p、k 个正交源且源间相关 ρ<1 时，错误提交概率 ≤ `δ_p·ρ^{k−1} + ε_σ`（R69 引理 18），而开放交互的单源错误率 ≥ δ_p。系：契约把「不可界的社会工程伤害」换成「可界的 VoI 折损」——这是交互设计的定量价值。

**引理 22（隔离活性与陈旧上界）** 在 TTL τ 与 SIM 生效时，任何未提升的 Q 单元存活时间 ≤ τ；超过 τ 后要么被新契约刷新，要么被清除并触发 R68 降级。因此隔离不会制造无限期的「陈旧影子信念」；Q 与 C 的后验发散被 SIM 的阈值约束。证明：TTL 强制过期 + 无 Q→C 直接写边；刷新是唯一延长路径，且刷新本身是新契约。

**定理 18（控制非干扰与污染遏制）** 在定义 310–317 下，固定认证观测流与提交序列，执行器指令与未提升的 Q 内容无关。因此 R69 的交互投毒在不获得 PSG 证书时只能影响 Q 与预算，不能改写认证控制；即使获得证书，其影响也被污点、证据、影响范围与到期时间约束，并可由 TBC 撤销。系：**「问错」的上限从「被证实的错误」降为「被隔离的错误」**；安全不再依赖回答的诚实性，只依赖「没有证书就不生效」这一条架构事实。

**定理 19（严格包含 R69 / R68）** 令提升策略为 π_gate。若 π_gate 对每个满足 R69 k 源一致的补丁立即放行且 TTL=∞，AIRLOCK 的控制路径与 FLUID-RAS 逐指令一致；若 π_gate 永远拒绝，则与 R68 的纯保守一致。AIRLOCK 默认策略严于 R69，因此认证风险 ≤ R69；拒绝时 λ 单调回到 R68 的 `λ_floor(U_ale+U_epi)`，安全侧不做让步。R69 是「立即提交」边界，R68 是「永不提交」边界，AIRLOCK 是二者之间的可调隔离谱。

**定理 20（交互可选性与安全不依赖）** 若 PSG 拒绝、SIM 报警、MCG 失败、TTL 到期或回滚级联失败任一发生，AIRLOCK 自动退化为 R68 保守路径，且未提升的 Q 内容不进入 C。因此交互是**优化层**而非安全前提：系统可以永远不提问而保持 R68 的安全下界；交互只在能通过气闸时兑换效率。这正面回应了「问错比不问更危险」：在新架构里，不问永远安全，问错至多浪费预算。

## 6. 本轮最大风险

**一句话**：AIRLOCK 的安全保证建立在「隔离边界就是信息边界」这一假设上——**如果 C/W/Q 仍共享同一个编码器、缓存、内存或时序通道，未提升的 Q 内容就能从共享底座渗进控制表征，使非干扰定理在实践中变成纸面承诺；而如果为了堵漏把气闸收得过死、提升门被习惯性放行或永远不放行，系统要么退化成安全但无知的 R68，要么把隔离变成摆设。**

**次级风险与缓解**：
1. **提升门自动化偏见**（操作者习惯性批准）→ 高影响提交 two_key + probation + 审计抽样；
2. **污点洗白/共谋**（相关源假装正交）→ 来源独立性检验 + 会话 nonce + 跨源因果检查；
3. **共享底座泄漏**（编码器/缓存/时序侧信道）→ 隔离 adapter、禁用共享条件、SIM 泄漏探针；
4. **回滚级联失败**（后续提交依赖被撤销补丁）→ 提交 DAG + 逆序撤销 + 失败即回退 R68；
5. **契约过严导致 VoI 归零**（不敢问）→ 隔离-效用 Pareto 调参 + 保留 R68 下界；
6. **交互疲劳与隐私泄漏** → 打扰预算、最小披露、可弃权与同意机制。

**定义 318（污点感知 VoI）** `VoI_IC(g)=κ(t)·[H(M|C)−E H(M|C,y)]−c(g)−c_verify(g)`；κ 随污点下降；`VoI_IC≤0` 则不问。交互设计直接进入决策函数：无法验证的问题在信息论上就不值钱。

**定义 319–320（事务与降密）** TBC 支持 prepare/commit/abort/revoke；补丁带逆补丁，沿提交 DAG 逆序撤销；回滚只承诺未来控制的认知恢复，已执行物理信息动作受 ε_int 约束。降密只能经证明 π（k 正交源、一致性、时效、必要时双钥匙），禁止聚合洗白。

**定义 321–322（影子学习与可理解协议）** 反事实与学习在 C/W 的 copy-on-write 影子 S 中进行，在线零学习写；提升只在维护期经证书。LIP 要求每条交互消息含 `(why, options, consequence, privacy)`，允许弃权/纠正，禁止诱导与时间压力，支持 abort。

**定义 323–324（SIM 与威胁模型）** SIM 检测非法写边、洗白、串扰、陈旧、发散、账本不一致、共享编码器泄漏；`ε_leak>τ_leak` 时禁用共享条件或冻结提交。`ℰ_AIRLOCK=ℰ_FLUID×ℰ_write`，新增重放/过期、跨会话、洗白、共谋、提示注入、侧信道、隐私推断、过度提问、恶意弃权。

**定义 325–326（证书与降级）** `J_AIRLOCK` 在 J_FLUID 上增加 state_version、partition_hash、taint_profile、contract_id、commit_id、rollback_proof、isolation_audit、leak_estimate。PSG 拒绝 / SIM 报警 / MCG 失败 / TTL 到期 / 回滚级联失败 ⇒ `λ=λ_floor(U_ale+U_epi)`，冻结或清除 Q_s，交互可选，安全不依赖。

## 5. 推导

**引理 19（污点单调性与不可洗白）** 派生状态污点等于来源污点之并；聚合、平均、重复采样不降低污点；同一 T3 来源重复多次仍为 T3，混入 T0 数据仍保留 T3 标记；唯一降密路径是 PSG 证明。系：多数一致只有在来源独立时才是证据，否则只是同一谎言的回声。

**引理 20（回滚可靠性）** 带逆补丁且无后续依赖的提交，撤销后 C 的认知分量回到提交前快照，λ 回到保守值，安全包络不扩大；有依赖时按 DAG 逆序级联，失败即回退 R68。物理解信息动作不可撤销但受 ε_int 约束，故回滚只承诺未来控制。

**引理 21（契约约束的 VoI 与最坏伤害）** `𝒢_IC ⊆ 𝒢 ⇒ VoI_IC ≤ VoI`，契约必然折损 VoI；但在欺骗率 δ_p、k 源独立且 ρ<1 时，错误提交概率 ≤ `δ_p·ρ^{k−1}+ε_σ`，而开放单源交互错误率 ≥ δ_p。系：契约把不可界的社会工程伤害换成可界的 VoI 折损。

**引理 22（隔离活性与陈旧上界）** TTL τ 与 SIM 生效时，未提升 Q 的存活时间 ≤ τ；超时即刷新或清除并触发 R68 降级；Q/C 后验发散受阈值约束，隔离不会制造无限期陈旧影子信念。

**定理 18（控制非干扰与污染遏制）** 固定认证观测流与提交序列，执行器指令与未提升 Q 内容无关。R69 的交互投毒在无 PSG 证书时只能影响 Q 与预算，不能改写认证控制；有证书时影响也被污点、证据、影响范围与 TTL 约束，并可经 TBC 撤销。系：问错的上限从「被证实的错误」降为「被隔离的错误」。

**定理 19（严格包含 R69 / R68）** 若 gate 对每个 R69 k 源一致补丁立即放行且 TTL=∞，控制路径与 FLUID-RAS 逐指令一致；若 gate 永远拒绝，则与 R68 纯保守一致。默认策略严于 R69，故认证风险 ≤ R69；拒绝时 λ 单调回到 `λ_floor(U_ale+U_epi)`，安全侧不让步。

**定理 20（交互可选性与安全不依赖）** PSG 拒绝 / SIM 报警 / MCG 失败 / TTL 到期 / 回滚级联失败任一发生，AIRLOCK 自动退化为 R68 保守路径，未提升 Q 不进入 C。因此交互是优化层而非安全前提：不问永远安全，问错至多浪费预算。

## 8. 本轮最大风险

**一句话**：AIRLOCK 的安全保证建立在「隔离边界就是信息边界」这一假设上——**如果 C/W/Q 仍共享同一个编码器、缓存、内存或时序通道，未提升的 Q 内容就能从共享底座渗进控制表征，使非干扰定理在实践中变成纸面承诺；而如果为了堵漏把气闸收得过死、提升门被习惯性放行或永远不放行，系统要么退化成安全但无知的 R68，要么把隔离变成摆设。**

**次级风险与缓解**：提升门自动化偏见（two_key + probation + 审计抽样）；污点洗白/共谋（来源独立性检验 + nonce + 跨源因果检查）；共享底座泄漏（隔离 adapter + 禁用共享条件 + SIM 泄漏探针）；回滚级联失败（提交 DAG + 逆序撤销 + 失败回退 R68）；契约过严导致 VoI 归零（隔离-效用 Pareto + 保留 R68 下界）；交互疲劳与隐私泄漏（打扰预算 + 最小披露 + 同意机制）。
