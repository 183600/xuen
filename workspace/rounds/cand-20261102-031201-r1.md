# 第 13 轮 · GUARD-RETRY：先别输掉能赢的 trial——把「安全性 / 应用落地 / 仿真到现实」接到 CHUNK-SERVO 的外层

> 检索/复核日期：**2026-11-02（UTC）**。轮次说明：状态文件已迭代到第 12 轮；本轮按接续第 13 轮记录（你称其为灵感循环第 1 轮），灵感词是「安全性」「应用落地」「仿真到现实」。本轮不推倒第 12 轮 CHUNK-SERVO、第 11 轮 GEO-RESIDUAL、第 10 轮 FACT-VLA，而是在它们外面加一层「安全—恢复—部署」外壳。

## 0. 先给结论：30% 的天花板，除了最后 3 厘米，还有“输掉的 trial”

第 12 轮的判断仍然成立：榜单头部不到 30%，共享瓶颈之一是 30 步开环 chunk 在最后 3 厘米不闭环。但第 12 轮把所有失败都归到“接触精度”，这可能漏掉了另外两类同样值钱的失败：

1. **本可避免的灾难性失败**：碰撞、夹持过深、把物体扫到桌下、针管/液体/玻璃器皿处理不当、人的手进入工作区时没有减速。一次这样的失败不仅丢掉当前 trial，还可能让机器人进入保护/停机状态，影响同一台机器人后面的 trial。
2. **本可重试的非终局失败**：没夹住、滑落、目标被人的干扰移走、插入偏了但物体还在桌上。规则给每次运行 **180 秒**，而 32 个任务的中位时长只有十几秒（最短 HangCup 6.2 s，最长 ToolboxStorage 37.6 s）。只要失败不是 evaluator 直接判定的终局失败，模型完全有机会在同一个 180 s 内“退回去、重定位、再试一次”。

所以本轮的押注不是“再来一个更大的 VLA”，而是：

> **GUARD-RETRY：在 CHUNK-SERVO 外面套一层确定性的安全盾（GUARD）和失败恢复/重试状态机（RETRY），再用仿真故障注入（SIM-FAULT）认证它；部署层（SLO）保证远程服务不因延迟、端口串扰、NaN 动作丢掉 trial。**

一句话：**先把“能赢但输掉”的 trial 捡回来，再谈模型上限。**

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 明确不做什么 |
|---|---|---|
| **安全性** | 动作级安全盾：关节/速度/加速度/加加速度限幅、工作空间、自碰撞、环境障碍、人类接近减速、跟踪误差碰撞检测、安全回撤、动作平滑 | 不训练第二个“安全策略”；不假设 API 有力/触觉；不做 30 Hz 广域网力控 |
| **应用落地** | 部署 SLO：固定 chunk、异步 plan cache、N 端口隔离、`/healthz`、热备、熔断、优雅降级、动作规律性；重试预算；部署卡片 | 不把比赛当纯离线 benchmark；不忽视 p99 延迟/可用性；不做一次性 demo |
| **仿真到现实** | 黑盒故障注入 + 物理孪生：标定安全阈值、恢复策略、延迟/摩擦/质量/相机外参；用真实数据拟合 sim gap | 不在仿真里从零训 6B 策略；不假设官方 sim 已有 32 个挑战任务；不把 sim 成功率当真机成功率 |

## 1. 本轮先查了什么：五条会改变方案的事实

### 1.1 官网仍可读，但榜单仍是“预览数据”（A+B）

官网首页、挑战赛页、排行榜、运行记录本轮通过 `r.jina.ai` 抓取（直连被腾讯 EdgeOne 安全策略拦截，返回 567）。关键事实：

- 首页/挑战赛页：32 项桌面任务，约 **32,000** 条演示、**169 小时**；榜单头部 **MolmoAct 29.7%**、WALLOSS 28.5%、DreamZero 27.9%、Spirit 25.9%、DM 23.5%、PI 22.8%、GigaBrain 22.6%、GR00T 20.5%。
- 排行榜 JSON 的 `generated_from` 仍是 `gen_leaderboard.py`；运行记录页显示 **256 / 256**（8 模型 × 32 任务），但单任务成功率出现 **21.5%、19.9%、27.2%、24.9%、12.9%** 这类值。每个任务只有 10 次 trial，真实成功率只能是 0/10、1/10、…、10/10；这些非 10% 整数倍说明运行记录同样是生成/预览数据。
- 详情页仍写着“测试视频占位，后续可替换为真实视频文件”。

**结论不变**：29.7% 可以当“赛事方预览上限/难度信号”，不能当 SOTA、不能当任务难度表、不能当失败分布。本轮的策略不从榜单任务排名里推，而从**规则、API、数据时长、官方仿真**里推。

### 1.2 规则：单模型、32 任务、10 次/任务、180 秒、自部署、N 端口（A）

参赛手册（飞书 docx，本轮通过 `r.jina.ai` 抓到 §1.1–§2.2）确认：

- 所有任务须基于**同一模型**完成，不得混合多个模型；模型类型不限（World Model、VLA 均可）。
- 32 个任务，每任务 **10 次**独立运行；5 类泛化各 **2 次**：位置、干扰物、桌面背景、未见物品、人为干扰。
- 单次真机执行上限 **180 秒**；超时记失败；按 32 任务总平均成功率排名，成功率相同看总平均步骤分，再相同看更早提交。
- 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 **N 个连续端口**；每端口独立交互，`reset()` 状态必须隔离。
- 另有**不计分的单任务测试通道**，可用于单任务成功率/步骤分验证。
- 手册公开部分**没有独立的安全分项**；安全主要通过“避免碰撞/损坏/超时/机器人停机”间接影响成绩。这一点必须诚实标注，不能声称“安全分”存在。

### 1.3 API：无深度/力/触觉，chunk 固定，评测端记录延迟与动作规律性（A）

提交模板 README（本轮复核）给出：

- 观测：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB 480×640；双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str`。
- 动作：`joint` 或 `ee` 互斥；`action_chunk_size` 固定；`meta.token` 每次 `get_action` 都要带。
- **没有 depth、camera_info、force/torque、tactile**。
- README 明确：评测端逐调用记录延迟、波动和**动作统计规律**，作为结果可信度的一部分；建议保持每步延迟稳定、动作 well-formed、避免异常 outlier。
- 官方示例 `example_policy.py` 的 `ACTION_CHUNK_SIZE = 8`；官方 WLA 的默认 `chunk_size = 30`、`target_fps = 30`。这两个数不矛盾：挑战赛的 API chunk 是“每次返回多少步”，WLA 的 30 是“规划多长”；CHUNK-SERVO 的做法是“规划 30、每次返回 5–8”。

**关键推论**：

- 安全盾只能靠**本体感觉 + 双目 + 动作历史**做，不能靠力/触觉。
- `action_chunk_size` 在 metadata 里固定，运行时不能改形状；但可以在固定形状里做“内容级”降级（例如延迟高时返回保持/回撤轨迹，而不是继续激进动作）。
- 评测端会看动作规律性，所以安全盾不能引入剧烈抖动/跳变；平滑本身就是“可信度”的一部分。

### 1.4 数据：32 数据集 / 33,276 episodes / 169.28 h；短任务多，重试 ROI 高（A+B）

HF collection API（本轮读取）确认 32 个数据集，合计 **33,276 episodes**。用 `numRows / fps / episodes` 估算单任务平均时长：

| 时长档 | 任务（示例） | 平均时长 |
|---|---|---:|
| 很短 | HangCup | 6.2 s |
| 短 | StackBowls、OrganizeBookshelf、DisconnectEthernet、FruitSorting、FruitCollection、PlacePhotoFrame、ConveyorSorting | 10.1–12.2 s |
| 中短 | ColorArrangement、PaperCupStacking、ZipUp、Unlock、PackBag、PlugCharger、SyringeWaterTransfer、PickOutBatteries、PlugInEthernet | 13.6–16.4 s |
| 中等 | ArrangeTestTubes、RemovePinnedNote、PackDoll、StoreCups、OrganizePencilCase、ArrangePlates、PourOutMedicine、OrganizeStationery、StoreEarphones、OrganizeTools、FoldTowel | 17.8–25.8 s |
| 长 | PackPhone、SpellRobot、StorePaddle、ToolboxStorage | 29.2–37.6 s |

**战略含义**：180 s 的预算对短任务极其宽裕。HangCup 6.2 s、StackBowls 10.1 s、DisconnectEthernet 10.5 s、ZipUp 14.1 s、PlugCharger 15.1 s、PlugInEthernet 16.4 s 这些“最后 3 厘米”任务，正好也是重试成本最低的任务。**CHUNK-SERVO 主攻第一次做对，GUARD-RETRY 主攻做错后还能再来一次；两者在同一批短任务上叠加。**

### 1.5 官方仿真：同 DDS、有 G1/Dex1，但没有 32 个挑战任务（A）

`unitree_sim_isaaclab` README（本轮复核）确认：

- 基于 Isaac Lab，G1/H1-2，支持 G1-29dof-gripper、G1-29dof-dex3、G1-29dof-inspire 等配置；有 G1-29dof-Dex1 的 PickPlace-Cylinder、PickPlace-RedBlock、Stack-RgyBlock、Move-Cylinder-Wholebody 等任务。
- 仿真与真机使用**相同的 DDS topics**，便于同一套控制栈切换。
- 但官方仿真**没有** HangCup、ZipUp、PlugInEthernet、Unlock、ToolboxStorage 等 32 个挑战任务的现成场景；要 1:1 复刻需要自己搭场景/资产。

**这直接限制了“仿真到现实”的用法**：不能假设“在官方 sim 里把 32 任务训到 80% 就能迁移”。本轮把 sim 定位为**安全盾/恢复策略的风洞 + 阈值标定器**，不是策略训练场；任务级验证仍然靠单任务不计分通道。

## 2. 诊断：70% 的失败不是同一种失败

把一次失败拆成四类，分别对应不同的边际收益：

```text
失败
├─ A. 最后 3 cm 接触失败（插入/挂/叠/拉链/锁/拧）
│    → CHUNK-SERVO：30 步规划 + 5 步视觉伺服 + 相对目标
├─ B. 灾难性/不安全失败（碰撞、扫落、针管/液体、人手进入、机器人保护）
│    → GUARD：确定性安全盾 + 安全回撤
├─ C. 非终局失败（没夹住、滑落、目标被人移走、插入偏了但物体还在）
│    → RETRY：失败检测 + 重定位 + 重规划 + 重试预算
└─ D. 基础设施失败（延迟尖峰、OOM、端口串扰、NaN/形状错误、token 不匹配）
     → SLO：异步 plan cache、健康检查、熔断、优雅降级、动作平滑
```

第 12 轮把 A 做深了；本轮补 B/C/D。四类失败可能重叠（例如碰撞导致物体掉落，然后又被判终局失败），但工程上可以分别设门、分别 A/B。

### 2.1 为什么 B 类值得投：一次灾难性失败可能丢掉不止一个 trial

规则没有安全分，但物理世界有“停机成本”：

- 机器人撞桌/自碰撞/夹爪卡死，可能触发保护，当前 trial 失败，后续 trial 需要人工复位；
- 评测跨 N 台机器人，若一台机器人因安全问题离线，后续排队到它的 trial 都会受影响；
- 人为干扰轴占 **20%**（2/10），人的手进入工作区时如果不减速，既危险又容易把物体碰走；
- 针管（SyringeWaterTransfer）、玻璃/陶瓷（ArrangePlates、StackBowls、PaperCupStacking）、拉链/锁（ZipUp、Unlock、ToolboxStorage）都有额外的夹伤/破损/液体风险。

所以安全盾的收益不是“安全分”，而是**保住 trial 预算和机器人可用性**。这是一种“风险工程”，不是“合规装饰”。

### 2.2 为什么 C 类值得投：180 秒是“第二次机会”的预算

手册说“模型在线接收观测并输出动作，直至任务成功、失败或超时”。这句话有两种读法：

- **宽松读法**：只要 evaluator 没判终局失败，模型可以在 180 s 内继续尝试；
- **严格读法**：evaluator 一旦判定任务失败就终止，模型没有重试机会。

公开手册没有把“失败判定”的细节写死。这正是单任务不计分通道要测的第一件事。**如果宽松读法成立，RETRY 的边际收益可能比再训一个更大的 VLA 更高；如果严格读法成立，RETRY 只能覆盖“未触发终局判定”的软失败，收益变小，但仍不为零。**

### 2.3 为什么 D 类值得投：远程自部署是比赛的一部分

- 选手自己部署模型，官方远程调用；N 个端口必须同时可用；
- 官方 `PolicyService` 在单个 asyncio 事件循环里同步调用 `get_action`；如果推理阻塞，整个连接会被阻塞；共享模型跨端口时必须自己做请求分发和状态隔离；
- 评测端记录延迟、波动、动作统计规律，作为结果可信度的一部分；
- 一次 OOM、一次端口串扰、一次 NaN 动作，可能让一个 trial 甚至一轮评测归零。

这类失败的修复成本通常低于模型改进，但经常被参赛队忽视。**先把服务做成“生产级”，再谈模型。**

## 3. 方案：GUARD-RETRY 的四层

### 3.1 总架构

```text
                    ┌──────────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1)      │
                    └───────────────┬──────────────────────────┘
                                    │ websocket: obs / action chunk
                                    ▼
                    ┌──────────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)            │
                    │  ├─ SLO guard: healthz / timeout / hold   │
                    │  ├─ GUARD: safety shield (deterministic)  │
                    │  ├─ FAIL: failure detector                │
                    │  ├─ RETRY: recovery FSM + retry budget    │
                    │  ├─ CHUNK-SERVO: plan cache + visual servo│
                    │  └─ action adapter (WLA 54D → API 21D)   │
                    └───────────────┬──────────────────────────┘
                                    │ async, batched
                                    ▼
                    ┌──────────────────────────────────────────┐
                    │  Shared VLA server (GPU)                  │
                    │  UnifoLM-WLA-1.0 / VLA-0, 30-step plan    │
                    └──────────────────────────────────────────┘

         ┌──────────────────────────────────────────────┐
         │  SIM-FAULT bench (offline)                    │
         │  black-box replay + IsaacLab physics twin     │
         │  inject: latency / dropout / human / shift    │
         └──────────────────────────────────────────────┘
```

- **唯一学习模型**：VLA（官方 WLA 微调 action head，或 VLA-0）。
- **确定性控制器**：安全盾、恢复原语、重试状态机；无学习权重；不违反单模型。
- **数据资产**：33k 成功演示 → 目标库 + 任务时长先验 + 失败合成语料。
- **仿真**：只做安全/恢复的风洞与阈值标定，不训大策略。

### 3.2 GUARD：动作级安全盾

对每个 `get_action` 返回的 chunk（H 步绝对 EE 位姿 + 夹爪 + pivot），在发回 evaluator 之前做一次确定性过滤：

1. **关节/速度/加速度/加加速度**：用 G1 URDF 做 IK，检查关节限位、速度、加速度、jerk；不可行就投影到最近可行轨迹。
2. **工作空间**：桌面以上的安全盒 + 机器人本体/头部禁区；越界就裁剪。
3. **自碰撞**：胶囊体模型检查双臂–躯干、双臂–头、双臂互撞；对插值轨迹采样检查。
4. **环境障碍**：用头部双目做粗视差/点云，建局部占据栅格；检查扫掠体积。
5. **人类接近**：头部双目 + 运动/肤色/深度做手部/人体候选；距离小于 `d_safe` 就按比例降速，小于 `d_hold` 就停。为避免“第二个学习模型”的合规争议，优先用确定性 CV；若用预训练检测器，明确它是安全传感器，不参与任务决策。
6. **跟踪误差碰撞检测**：比较上一条命令的 EE 位姿和当前观测 EE 位姿；若 `||T_cmd - T_obs||` 连续 K 步超阈值，判碰撞/卡住，停 + 回撤。
7. **动作平滑**：低通/限 jerk；chunk 边界与上一 chunk 的最后一步做混合；避免评测端看到“动作统计异常”。
8. **安全回撤**：预计算一个无碰撞的 home/预抓取位姿；失败时慢速回撤，而不是原地乱动。

安全盾的输出不是“更聪明的动作”，而是“**保证不会做出明显危险/不可行动作**”。它可能让第一次成功率略降（误报），但换来更少的灾难性失败和更干净的恢复起点。

### 3.3 FAIL：失败检测

不训练第二个模型，用阈值 + 几何 + 演示先验：

| 失败模式 | 信号 | 判定 |
|---|---|---|
| 没夹住 | 夹爪开口 vs 物体宽度；腕部图里物体是否在指间；抬头图物体是否仍不动 | 夹爪闭合后提升 2 cm，物体未随动 |
| 滑落 | 物体相对夹爪位移；GEO-RESIDUAL 的 `r_grasp` 突变 | 连续 2–3 帧位移超阈值 |
| 掉落 | 头部图物体向下运动/消失；桌面区域变化 | 物体落到桌面/桌下 |
| 碰撞/卡住 | 命令 EE 与观测 EE 的跟踪误差；关节速度饱和 | 连续 K 步 `e_track > θ` |
| 目标被移走 | 场景运动无法被机器人动作解释（`edit_score`） | 编辑检测触发 |
| 插入偏了 | 伺服误差不下降；接触后位置停滞 | 窗口内误差斜率 ≈ 0 |
| 时间不够 | 剩余时间 < 预估恢复 + 任务时长 | 触发保守回撤/放弃 |

阈值不能拍脑袋：用**合成失败语料**（成功演示 + 扰动/截断/加噪）和单任务通道的真实失败来标定；报告误报率/漏报率/AUROC。

### 3.4 RETRY：恢复状态机 + 重试预算

```text
RUN ──failure──▶ HOLD ──▶ ASSESS ──▶ RETREAT ──▶ RELOCALIZE ──▶ REPLAN ──▶ RETRY
  ▲                 │           │             │
  │                 │           └─ object gone / human present ──▶ ABORT
  │                 └─ transient? wait 0.2s ──▶ RESUME
  └──────────────────── success ◀──────────────────────────────────┘
```

- `HOLD`：停 0.2 s，确认不是单帧噪声。
- `ASSESS`：物体还在不在？目标可见吗？人还在工作区吗？剩余时间够吗？
- `RETREAT`：回到安全预抓取位姿（来自演示关键帧/任务几何）。
- `RELOCALIZE`：头双目 + 演示检索重估目标位姿；人移动过就更新。
- `REPLAN`：用同一 VLA，拿新观测 + 内部失败上下文重新规划（例如“上次夹空了，从左侧再试”）；不改 API 的 `observation.language`。
- `RETRY`：用 CHUNK-SERVO 执行；重试次数受预算约束。
- `ABORT`：物体掉出工作区/人未离开/时间不够时，安全回撤并结束，避免更糟的碰撞。

**重试预算**（一阶模型）：

```text
T_rem = 180 - t_elapsed - T_safe
N_max = floor(T_rem / (T_task_p50 + T_recovery + T_infer))
```

用数据里的任务时长（HangCup 6.2 s、StackBowls 10.1 s、PlugInEthernet 16.4 s、ToolboxStorage 37.6 s）和 `T_recovery ≈ 3–8 s`、`T_infer ≈ 0.2–0.5 s` 估算，短任务可重试 7–14 次，长任务只有 3–4 次。**所以 RETRY 的战略是“短任务多试、长任务少试、先保证不把长任务拖超时”。**

### 3.5 SLO：部署层

- **固定 chunk**：metadata 里选一个 `action_chunk_size`（建议 5 或 8），运行时不变；内部用 30 步 plan cache，按块取。
- **异步 plan cache**：VLA 推理在后台线程/进程；`get_action` 永不因推理阻塞；plan 过期就用旧 plan + 伺服/保持。
- **共享模型跨端口**：请求队列 + 批处理 + 每端口 session；严格隔离 `reset()` 和历史；避免 head-of-line blocking。
- **健康检查**：`/healthz`；启动自检；token/端口/依赖检查。
- **熔断/降级**：推理超时 → 返回安全保持/回撤；连续失败 → 降低动作幅度；OOM → 重启 worker，保留主服务。
- **动作规律性**：无 NaN/inf；形状严格；jerk 有界；chunk 边界平滑；避免“统计上异常”的离群动作。
- **观测/动作日志**：每步记录延迟、动作范数、失败模式；单任务通道用来定位问题。

## 4. 创新点清单（持续迭代，不推倒重来）

> 说明：这是本轮更新后的清单。每个点都按「动机 / 与现有方案的差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险」写。排序按“预期分数增益 × 成功概率 / 成本”的先验，不是最终结论。

### I1 · GUARD-SHIELD：动作 chunk 的确定性安全盾

- **动机**：一次碰撞/卡死/人手事故可能丢掉当前 trial，甚至让机器人离线，影响后续 trial；API 没有力/触觉，只能用本体感觉 + 双目 + 动作历史做安全。
- **差异**：不是第二个学习策略，也不是传统“低速保守”；是把安全约束施加在 VLA 的 action chunk 上（chunk-level shielding），并与 CHUNK-SERVO 的 5 步执行块对齐；用跟踪误差做碰撞代理，用双目做人类接近。
- **可行性**：高。G1 URDF + 胶囊体 + IK + 工作空间盒 + 简单视差都能在 CPU 上跑；5 Hz 足够。
- **资源**：G1 URDF/关节限位；头部双目内参/外参；安全盒/禁区手工配置；单任务通道；仿真故障注入。
- **落地步骤**：① 离线用成功演示回放，统计正常跟踪误差分布；② 实现限幅/工作空间/自碰撞；③ 加人类接近减速；④ 加跟踪误差碰撞检测；⑤ 在 IsaacLab 的 PickPlace/Stack 上注入碰撞/人手；⑥ 单任务通道 A/B。
- **风险**：误报导致成功率下降；人类检测漏报/误报；不同机器人标定差异；安全盾把合法接触判成碰撞。缓解：阈值用分布标定、保留“仅减速不停止”的软模式、按任务启用。

### I2 · FAIL-RETRY：失败检测 + 安全恢复 + 180 秒重试预算

- **动机**：70% 失败里有相当一部分不是终局失败；180 s 对短任务很宽裕；当前 VLA 失败后往往继续开环乱动或直接结束，浪费了“第二次机会”。
- **差异**：不是“再训一个恢复策略”；是用确定性原语（回撤/重定位/重抓）+ 同一个 VLA 重规划；重试预算由数据里的任务时长和恢复成本决定；把“失败”当成可观测状态，而不是只当成 0/1 结果。
- **可行性**：中高。失败检测用几何/阈值；恢复原语用演示关键帧；重规划用同一模型；难点是 evaluator 是否允许重试、步骤分是否惩罚重试。
- **资源**：33k 演示的关键帧/任务时长；单任务通道；安全盾；GEO-RESIDUAL 的编辑检测；VLA server 的快速重规划。
- **落地步骤**：① 单任务通道测“失败后继续动”是否被允许；② 实现 6 类失败检测；③ 实现回撤/重定位/重抓原语；④ 加预算公式；⑤ 5 任务 A/B（retry off/on）；⑥ 看步骤分是否退化。
- **风险**：evaluator 判终局失败 → 重试无效；重试拖到超时 → 反而丢分；步骤分惩罚 → tie-break 吃亏；重复失败导致机械磨损。缓解：先测规则、设最大重试次数、超时前主动 abort、短任务优先。

### I3 · SLO-DEPLOY：把提交当成生产服务

- **动机**：自部署 + 远程 API + N 端口；一次延迟尖峰/OOM/端口串扰/NaN 动作就可能丢掉 trial；评测端还看动作规律性。
- **差异**：大多数队伍把工程当“能跑就行”；这里把可用性、p99、状态隔离、动作平滑当成一等公民；与 GUARD/RETRY 共享同一套监控。
- **可行性**：高。官方模板已经给了 `PolicyService`、`/healthz`、msgpack/JPEG；主要工作是异步化、隔离、熔断、监控。
- **资源**：1–2 名工程；容器/进程管理；GPU 共享/批处理；日志/指标；压测脚本。
- **落地步骤**：① 用官方 `run_server.py` + `run_client.py` 跑通；② 异步 plan cache；③ 每端口 session 隔离；④ 压测 320 trials/多端口；⑤ 注入延迟/丢包/OOM；⑥ 加熔断/降级；⑦ 写部署卡片。
- **风险**：过度工程拖慢进度；共享模型并发导致延迟更高；状态隔离 bug 造成串扰。缓解：先单端口稳定，再多端口；用 canary + 回滚；压测优先于功能。

### I4 · SIM-FAULT：黑盒故障注入 + 物理孪生认证

- **动机**：安全盾/恢复策略的阈值不能拍脑袋；真机不能拿来试碰撞；官方 sim 没有 32 任务，但同 DDS、有 G1/Dex1，能做“控制/安全”的风洞。
- **差异**：不是“sim-to-real 训策略”；是“sim-to-real 认证控制器”。黑盒 twin 回放真实 obs/action，注入延迟/丢包/图像噪声；物理 twin 只做通用接触原语（抓/放/叠；插入/拉链需自建），不追求 32 任务 1:1。
- **可行性**：中高。黑盒 twin 成本低；物理 twin 成本中；32 任务全复刻成本高，不做。
- **资源**：IsaacLab/Isaac Sim GPU；G1-29dof-Dex1 资产；真实演示回放；延迟/噪声注入脚本；标注的安全事件。
- **落地步骤**：① 黑盒 replay 跑通；② 注入延迟/丢包/模糊/遮挡；③ 物理 twin 搭 3 个原语场景；④ 注入物体位移/人手/碰撞；⑤ 标定阈值；⑥ 报告 unsafe event rate / recovery rate / sim-real gap。
- **风险**：sim gap 大；场景搭建耗时；把 sim 结论过度外推。缓解：只用于相对排序和阈值初值；真机单任务通道复核；报告 gap。

### I5 · FAIL-CORPUS + RETRY-BUDGET：失败语料与重试经济学

- **动机**：33k 演示全是成功，没有失败样本；失败检测/恢复需要失败分布；重试预算需要任务时长和恢复成本。
- **差异**：不是收集新的真机失败（贵）；是从成功演示合成失败（截断、加噪、物体位移、夹爪偏移、遮挡）+ 仿真注入；把“重试”当成投资组合问题，而不是拍脑袋多试几次。
- **可行性**：高。合成失败便宜；预算公式简单；可在单任务通道验证。
- **资源**：演示数据；仿真扰动；标注少量真实失败；统计脚本。
- **落地步骤**：① 从成功演示生成失败变体；② 标定检测阈值；③ 用任务时长算 `N_max`；④ 按 `q_t × Δ / cost` 排任务；⑤ A/B 验证。
- **风险**：合成失败与真实失败分布不一致；阈值过拟合；重试收益被高估。缓解：真实失败校准、保守预算、配对 A/B。

### I6 · RISK-VLA：风险感知的测试时动作选择（观察项，暂不作为主投）

- **动机**：扩散/流 VLA 一次采样可能出坏 chunk；如果能采样 K 个候选，用安全盾过滤、用演示检索/进度打分选最好的，可能比单次采样稳。
- **差异**：不训练第二个策略；用同一个 VLA 的多次采样 + 确定性过滤/排序；属于 test-time compute，而不是新模型。
- **可行性**：中。K 次采样增加延迟；6B 模型远程部署可能吃不消；需要动作专家的小模型/缓存；单模型合规需要说明“同一 checkpoint 多次采样”。
- **资源**：GPU 余量；低延迟推理；候选排序器（确定性/检索）；单任务通道。
- **落地步骤**：① 在单任务通道测 K=2/4 的延迟；② 用安全盾过滤；③ 用演示检索/进度排序；④ 只在短任务启用；⑤ 看是否真的涨点。
- **风险**：延迟翻倍；候选多样性不足；排序器引入偏差；评测端看到动作分布异常。缓解：只在低延迟时启用；K 小；保持动作平滑；不作为第一优先级。

**已剪枝/不投**（延续第 12 轮）：从零训 6B/14B、完整 sim-to-real 策略训练、第二个学习残差策略、6D 物体位姿网络、力/触觉闭环（API 没有）、30 Hz 广域网伺服、32 任务各训一个策略、把预览榜单任务排名当难度表。

## 6. 竞赛策略：重试预算与任务排序

### 6.1 任务排序（先验，待单任务通道更新）

```text
priority_t = q_t * Δ_t * r_t / cost_t
```

- `q_t`：失败发生在“可恢复/可重试”区间的比例（先验：短任务高）；
- `Δ_t`：GUARD+RETRY 的条件增益；
- `r_t`：重试预算（由 180 s / 任务时长决定）；
- `cost_t`：工程/评测成本。

先验上，**短、接触密集、失败可恢复**的任务优先：

- **第一梯队（短 + 接触 + 高重试 ROI）**：HangCup（6.2 s）、StackBowls（10.1 s）、DisconnectEthernet（10.5 s）、ZipUp（14.1 s）、PlugCharger（15.1 s）、PlugInEthernet（16.4 s）。
- **第二梯队（短/中短 + 可恢复）**：FruitCollection、FruitSorting、PlacePhotoFrame、ConveyorSorting、ColorArrangement、PaperCupStacking、Unlock、PackBag、SyringeWaterTransfer、PickOutBatteries、ArrangeTestTubes。
- **第三梯队（长任务，重试预算少）**：ToolboxStorage、StorePaddle、SpellRobot、PackPhone、FoldTowel、OrganizeTools、StoreEarphones、OrganizeStationery、PourOutMedicine、ArrangePlates。
- **观察**：早期感知/抓取就失败、且重试也救不回来的任务，不投 GUARD/RETRY，保留 VLA 基线。

这张表是**先验**，不是结论；单任务通道测完后用实测 `q_t`、`Δ_t`、`r_t` 重排。

### 6.2 重试收益的算术（C 级，必须配对 A/B）

设单次成功率 `p`，可恢复失败比例 `r`，最多 `N` 次尝试。一阶模型：

```text
p_eff ≈ 1 - (1-p) * (1 - r*p)^(N-1)
```

- `p=0.3, r=0.4, N=3` → `p_eff ≈ 0.458`（+15.8 pp）；
- `p=0.3, r=0.2, N=3` → `p_eff ≈ 0.382`（+8.2 pp）；
- `p=0.3, r=0.4, N=7`（PlugInEthernet）→ `p_eff ≈ 0.675`（+37.5 pp，明显乐观，忽略失败相关性）。

这是**上界**，不是承诺。真实失败往往相关（同一个模型偏差、同一个初始条件），独立性假设会高估。用配对 A/B + bootstrap 置信区间，不要用 +1–2 pp 下结论。

### 6.3 单任务通道协议

1. 选 5 个代表任务：HangCup（短/挂）、StackBowls（短/叠）、PlugInEthernet（中短/插）、ZipUp（中短/拉链）、ToolboxStorage（长/锁，防回归）。
2. 每个任务 5 次 A/B：`guard+retry off` vs `on`；同一初始条件；记录成功、步骤分、耗时、p99、unsafe 事件、重试次数。
3. 先测“失败后继续动是否被允许”“重试是否扣步骤分”；这是规则问题，不是模型问题。
4. 通过标准：≥3/5 任务 +10 pp；长任务不回归 >5 pp；无 unsafe 事件；p99 不升。
5. 再扫 `action_chunk_size ∈ {5, 8}`；固定后不再改。
6. 最后才跑 32×10 正式评测。

- **新增剪枝**：不做“为了安全而全面降速”的保守策略（会直接丢成功率）；不做“无预算的无限重试”（会拖超时）；不做“需要第二个学习检测器”的重型安全模型（合规/成本）。

## 9. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 安全盾误报 | 合法接触被停，成功率下降 | 阈值用成功演示分布标定；软/硬两级；按任务启用 |
| 人类检测漏报 | 人机碰撞风险 | 双目 + 运动 + 深度多信号；保守减速；不声称 100% |
| 重试被判定终局失败 | RETRY 无效 | 先用单任务通道测规则；只对软失败重试 |
| 重试拖超时 | 反而丢分 | 预算公式 + 安全余量 + 主动 abort |
| 步骤分惩罚重试 | tie-break 吃亏 | 记录步骤分；只在成功率优先时启用 |
| 单模型解释 | 被判定第二个模型 | 安全/恢复全为确定性控制器；不加载第二个学习策略；材料写清 |
| 共享模型并发 | 延迟升高/端口串扰 | 请求队列 + 批处理 + 每端口 session；压测 |
| 动作不规律 | 评测端可信度下降 | 平滑/限 jerk/无 NaN；监控动作统计 |
| sim gap | 阈值迁移失败 | 只做相对排序/初值；真机复核；报告 gap |
| 评测噪声 | +1–2 pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4 pp |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |

**合规要点**：

- 单模型规则下，安全盾/恢复原语是**控制器**，不是策略；不加载第二个学习策略。
- 失败检测优先用阈值/几何；若用预训练人类检测器，声明为安全传感器，不参与任务动作决策。
- 重试只用同一个 VLA 重新规划，不引入第二个模型。
- 仿真只用于标定/验证，不用于训练第二个策略；若用 sim 微调 action head，仍是同一模型，但需说明数据来源。

## 10. 一句话押注

**当前最值得押注的是：在不换更大模型的前提下，把 CHUNK-SERVO 外面套一层确定性安全盾与失败恢复/重试，并用仿真故障注入认证——先保证不输掉能赢的 trial，再让可恢复失败有第二次机会。**

## 2. 问题形式化

### 2.1 分数、试次预算与重试经济学

总分：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

320 trials 下，若 `p≈0.25`，单次标准误：

```math
\mathrm{SE}(S)\approx \sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

**重试不是“多试几次”的口号，而是预算问题。** 设任务 `t` 的单次成功率 `p`、失败可恢复比例 `r`、单次尝试时长 `T_t`、恢复开销 `T_r`、推理开销 `T_i`、安全余量 `T_s`，则最多尝试次数：

```math
N_{\max}(t)=\left\lfloor
\frac{180-T_s}{T_t+T_r+T_i}
\right\rfloor .
```

一阶成功率模型（独立近似，乐观上界）：

```math
p_{\mathrm{eff}}(N)=1-(1-p)\,(1-rp)^{N-1}.
```

相关性修正（保守）：真实失败往往相关（同一模型偏差、同一初始条件），可写成

```math
p_{\mathrm{eff}}\approx p+(1-p)\,r\,p\,(1-c),
```

其中 `c∈[0,1]` 是失败相关性；`c=1` 时重试完全无效。**报告必须给配对 A/B 的 bootstrap 置信区间，不能只用独立模型。**

### 2.2 安全盾的可行集

设机器人状态 `x=(q,\dot q,\ddot q,T_{ee})`，动作 chunk `A={a_1..a_H}`。定义安全集：

```math
\mathcal S=\{x\mid
q_{\min}\le q\le q_{\max},\;
|\dot q|\le v_{\max},\;
|\ddot q|\le a_{\max},\;
|\dddot q|\le j_{\max},\;
T_{ee}\in\mathcal W,\;
d_{\mathrm{self}}(q)\ge d_{\min},\;
d_{\mathrm{obs}}(T_{ee})\ge d_{\mathrm{obs,min}},\;
d_{\mathrm{human}}\ge d_{\mathrm{safe}}\}.
```

给定 VLA 的 chunk `A`，安全盾求最长可行前缀 `k*`：

```math
k^*=\max\{k\mid a_1,\ldots,a_k\ \text{在}\ \mathcal S\ \text{内可行}\}.
```

若 `k*` 小于阈值 `k_min`，不继续执行，转入安全回撤；否则执行前 `k*` 步，并在下一个 API chunk 重新规划。近似投影：

```math
a'_k=\arg\min_{a\in\mathcal S}\|a-a_k\|^2,
```

工程上用“限幅 + IK + 轨迹缩放 + 工作空间裁剪 + 自碰撞检查”近似，不追求全局最优。

### 2.3 失败检测作为假设检验

对每个失败模式 `m`，定义信号 `s_m(t)` 和阈值 `θ_m`：

```math
\hat y_m(t)=
\begin{cases}
1,& s_m(t)>\theta_m\ \text{连续}\ K_m\ \text{帧},\\
0,& \text{otherwise}.
\end{cases}
```

阈值 `θ_m` 用两类分布标定：

- 正常/成功演示的 `s_m` 分布（控制误报）；
- 合成/真实失败的 `s_m` 分布（控制漏报）。

目标：`FPR ≤5%`、`TPR ≥80%`、检测延迟 `≤200 ms`。对每个模式单独报告，不用一个总 AUROC 掩盖差异。

### 2.4 部署延迟与可用性

设 `H_c` 为 API chunk 步数，`f_c` 为控制频率，`τ` 为 RTT+推理+图像传输的等效延迟。反馈周期：

```math
T_{\mathrm{fb}}\approx \frac{H_c}{f_c}+\tau.
```

| 场景 | `H_c` | `f_c` | `τ` | `T_fb` | 评价 |
|---|---:|---:|---:|---:|---|
| WLA 默认 | 30 | 30 | 50 ms | **1050 ms** | 接触段基本开环 |
| 本方案保守 | 8 | 30 | 50 ms | **317 ms** | 可做 1–2 次修正 |
| 本方案激进 | 5 | 30 | 50 ms | **217 ms** | 需稳定 RTT |
| 高延迟 | 5 | 30 | 150 ms | **317 ms** | 降增益/保持 |
| 低控制频率 | 5 | 10 | 50 ms | **550 ms** | 只做 PBVS/保持 |

可用性：

```math
A = 1-\frac{\text{failed calls}}{\text{total calls}}\ge 0.999,
\qquad
\mathrm{p99}(\text{latency})\le 150\ \mathrm{ms}.
```

动作规律性约束：

```math
\|a_k\|<\infty,\quad \|\Delta a_k\|\le \Delta_{\max},\quad
\|\Delta^2 a_k\|\le J_{\max}.
```

### 2.5 仿真到现实的标定

用真实演示的相机观测/EE 位姿做重投影与延迟拟合：

```math
\min_{\delta T,\,s_f,\,\tau}\ \sum_i
\left\|\pi(\delta T,s_f,X_i)-u_i\right\|^2
+\lambda\sum_j\|\tau_j-\hat\tau_j\|^2.
```

安全阈值不是“拍一个数”，而是在 sim 里扫参数，找到“误报 ≤5%、漏报 ≤20%”的工作点，再用真机单任务通道复核。sim 只给相对排序和初值，不给绝对成功率。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
                    ┌──────────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1)      │
                    └───────────────┬──────────────────────────┘
                                    │ websocket: obs / action chunk
                                    ▼
                    ┌──────────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)            │
                    │  ├─ SLO guard: healthz / timeout / hold   │
                    │  ├─ GUARD: safety shield                  │
                    │  ├─ FAIL: failure detector                │
                    │  ├─ RETRY: recovery FSM + budget          │
                    │  ├─ CHUNK-SERVO: plan cache + servo       │
                    │  └─ action adapter (WLA 54D → API 21D)   │
                    └───────────────┬──────────────────────────┘
                                    │ async, batched
                                    ▼
                    ┌──────────────────────────────────────────┐
                    │  Shared VLA server (GPU)                  │
                    │  UnifoLM-WLA-1.0 / VLA-0, 30-step plan    │
                    └──────────────────────────────────────────┘

         ┌──────────────────────────────────────────────┐
         │  SIM-FAULT bench (offline)                    │
         │  black-box replay + IsaacLab physics twin     │
         │  inject: latency / dropout / human / shift    │
         └──────────────────────────────────────────────┘
```

- 每端口一个 `PolicyService` 实例，独立 `reset()`、独立 plan cache、独立 fail/retry 状态。
- 安全/失败/恢复是 CPU 线程，不阻塞 websocket；VLA 请求异步、可批处理。
- 共享 VLA server 用 session ID 区分端口；模型权重只有一份，不违反单模型。
- GPU 6B bf16 约 12 GB；一张 24 GB/40 GB GPU 可服务多个端口，具体并发取决于 batch 和序列长度。

### 3.2 接口契约与 chunk 语义

提交 metadata 示例：

```python
{
    "control_space": "ee",
    "obs_delta_indices": {
        "observation.language":                         [0],
        "observation.images.cam_left_high":             [0],
        "observation.images.cam_right_high":            [0],
        "observation.images.cam_left_wrist":            [0],
        "observation.images.cam_right_wrist":           [0],
        "observation.state.left_ee_pose_gripper_base":  [0],
        "observation.state.right_ee_pose_gripper_base": [0],
        "observation.state.left_gripper":               [0],
        "observation.state.right_gripper":              [0],
        "observation.state.lower_body":                 [0],
    },
    "image_resize": {
        "observation.images.cam_left_high":  [240, 320],
        "observation.images.cam_right_high": [240, 320],
        "observation.images.cam_left_wrist": [128, 128],
        "observation.images.cam_right_wrist":[128, 128],
    },
    "action_chunk_size": 8,
    "token": os.environ["UNIBOT_SUBMISSION_TOKEN"],
}
```

**两级 chunk**：

```text
H_plan = 30   # VLA 规划长度（WLA 默认）
H_api  = 8    # metadata 固定的 API chunk（官方示例默认）
```

- VLA 每 30 步产出一个 plan；后台缓存。
- 每次 `get_action` 返回 `H_api` 步；evaluator 执行完后再次调用。
- `H_api=8` 时 `T_fb≈267 ms + τ`；`H_api=5` 时 `T_fb≈167 ms + τ`。
- 运行时不能改 `H_api`；只能在固定形状里做内容级降级（保持/回撤/减速）。

**绝对/相对动作的锚点**：挑战赛 `ee` 动作是**绝对目标位姿**；WLA 输出的是**相对当前 EE** 的 xyz+rotvec。adapter 必须先把整个 plan compose 成 base 系绝对目标，再按 `H_api` 切片。**但每个 API chunk 要用“当前观测 EE”重新锚定剩余 plan**，不要把 30 步前的绝对位姿直接重放；否则安全盾/接触造成偏差后，后续动作会系统性错位。CHUNK-SERVO 的视觉伺服负责最后 3 cm 的相对修正，安全盾负责不做出危险动作。

### 3.3 `get_action` 伪代码

```python
class GuardRetryPolicy:
    def get_action(self, obs):
        self._tick(obs)                       # update history, latency, budget
        self._maybe_request_plan(obs)         # async; never block

        mode = self.fail.detect(obs, self.hist, self.goal, self.budget)
        if mode is not None:
            self.fsm.on_failure(mode, obs)
            return self._safe_hold_or_retreat(obs)

        if self.fsm.state == "RETRY":
            self._maybe_retry(obs)

        plan = self._current_plan(obs)
        a_ff = plan[self.plan_idx : self.plan_idx + self.H_api]
        if self.mode == "SERVO" and self.goal is not None:
            delta = self.servo.compute(obs, self.goal)
            a_ff = compose_relative(a_ff, delta)

        a_safe = self.guard.filter(a_ff, obs)  # may truncate/scale/hold
        self.plan_idx += self.H_api
        if self.plan_idx >= len(plan):
            self.plan_idx = 0
            self.plan = None
        return self.adapter.to_api(a_safe, obs, self.token)

    def reset(self):
        self.hist.clear()
        self.plan = None
        self.plan_idx = 0
        self.fsm.reset()
        self.budget.reset()
        return {"ok": True}
```

`_maybe_request_plan`：

```python
def _maybe_request_plan(self, obs):
    if self._future is not None and not self._future.done():
        return
    if self._future is not None:
        self.plan = self._future.result()
        self._future = None
        self.plan_idx = 0
    if self.plan is None or self.plan_age >= self.plan_ttl:
        snapshot = copy_obs(obs)
        self._future = self.executor.submit(self.vla.predict, snapshot)
```

规则：

- VLA 永远不阻塞 `get_action`（冷启动除外）；plan 过期就用旧 plan + 伺服/保持。
- 每个 API chunk 只做一次伺服 + 一次安全过滤；任何异常 → 返回上一组合法 chunk 或安全保持；绝不返回 NaN/错误形状。
- 安全盾可以截断 chunk，但返回的形状必须是 `(H_api, ...)`；截断部分用保持/回撤动作填充，保持形状合法。

### 3.4 恢复状态机

```text
RUN ──failure──▶ HOLD ──▶ ASSESS ──▶ RETREAT ──▶ RELOCALIZE ──▶ REPLAN ──▶ RETRY
  ▲                 │           │             │
  │                 │           └─ object gone / human present ──▶ ABORT
  │                 └─ transient? wait 0.2s ──▶ RESUME
  └──────────────────── success ◀──────────────────────────────────┘
```

- `HOLD`：停 0.2 s，确认不是单帧噪声；同时记录跟踪误差/动作历史。
- `ASSESS`：物体还在不在？目标可见吗？人还在工作区吗？剩余时间够吗？
- `RETREAT`：回到安全预抓取位姿（来自演示关键帧/任务几何），慢速、无碰撞。
- `RELOCALIZE`：头双目 + 演示检索重估目标位姿；人移动过就更新。
- `REPLAN`：用同一 VLA，拿新观测 + 内部失败上下文重新规划；不改 API 的 `observation.language`。
- `RETRY`：用 CHUNK-SERVO 执行；重试次数受预算约束。
- `ABORT`：物体掉出工作区/人未离开/时间不够时，安全回撤并结束，避免更糟的碰撞。

### 3.5 SLO 实现

```text
固定 chunk:        metadata.action_chunk_size = 8（提交前定，运行时不改）
异步 plan:         后台线程/进程; get_action 只读缓存
共享模型:          请求队列 + 批处理 + per-port session
状态隔离:          每个 port 独立 hist/plan/goal/fsm/budget
健康检查:          /healthz; 启动自检 token/port/deps
熔断:              连续 N 次推理超时/异常 -> 安全保持 + 降级
降级:              延迟高 -> 返回保持/减速; 不返回激进动作
动作规律性:        无 NaN/inf; 形状严格; jerk 有界; chunk 边界平滑
日志:              每步延迟/动作范数/失败模式/重试次数
```

**共模故障**：N 个端口共享同一个 VLA server 时，一个 OOM/重启会同时影响所有端口。缓解：主备 worker、健康检查、快速重启、必要时回退到轻量基线（例如单独的 VLA-0 小模型或安全保持）。这不是“第二个任务模型”，而是降级路径；需在材料中说明。

### 3.6 动作适配（WLA 54D → 挑战赛 21D）

```text
WLA 54D:
  left_ee_rel[6], left_gripper[1], left_hand[6],
  right_ee_rel[6], right_gripper[1], right_hand[6],
  waist[3], torso[3], base_vxvy[2], base_wz[1],
  base_pose_rel[6], height[1], left_leg[6], right_leg[6]

挑战赛 ee 21D:
  left_ee_abs[6], right_ee_abs[6],
  left_gripper[1], right_gripper[1], pivot[7]
```

映射：

1. `left_ee_abs = compose(T_base_ee_left_current, exp(left_ee_rel))`；转 xyz+rpy。
2. `right_ee_abs` 同理。
3. gripper 直通（按挑战赛的 0–1 方向校验）。
4. `pivot = [vx, vy, wz, yaw, pitch, roll, height]`，从 WLA base/waist 组合；具体符号/顺序必须用 `example_env.py` 和单任务通道验证。
5. 腿部/灵巧手在挑战赛 `ee` 模式下不直接下发；若 `pivot` 需要下身体，按官方 WLA server 的 `action.pivot` 语义映射。
6. **默认零 pivot**：在 `pivot` 语义未验证前，先返回全零 pivot（保持下身体不动），只验证双臂；不要猜符号。

**帧/TCP 风险**：WLA 的 EE 帧与挑战赛的 `*_ee_pose_gripper_base` 帧可能差一个 TCP/夹爪长度偏移；必须用 `example_env.py` 的观测和真实数据做一次手眼/工具坐标校准（平移 ≤1 cm、旋转 ≤2°）。这是 G10 的第一验证项。

### 3.7 架构选择：VLA + 确定性盾，不把世界模型放进 5 步闭环

| 架构 | 代表 | 优点 | 在本赛的瓶颈 | 结论 |
|---|---|---|---|---|
| 纯 VLA | π0.5、GR00T、WLA | 语义/泛化强；生态成熟 | 开环 chunk；最后 3 cm；失败恢复弱 | 基座 |
| VLA + 确定性盾/恢复 | 本方案 | 不违反单模型；延迟低；可解释；可仿真认证 | 盾的阈值需标定；误报风险 | **主投** |
| VLA + 世界模型在线 | DreamZero（公开材料称 14B）、WMA | 长程预测/想象 | 推理重；5 步闭环来不及；不直接解决毫米级接触 | 不放进主环 |
| 世界模型离线 | GigaBrain、WMA | 生成数据/评估 | 物理保真度；数据管线成本 | 观察 |

- 世界模型可以离线生成“失败/恢复”数据或做评估，但不进入 5 步控制环。
- 在线风险预测若要做，优先用同一 VLA 的多次采样 + 确定性盾，而不是再训一个 14B 级世界模型。
- 本赛的瓶颈是“接触 + 恢复 + 部署”，不是“想象未来”；架构选择应服务这个瓶颈。

### 3.8 训练策略：动作头微调 + 失败/恢复增强

- **基座**：官方 WLA Base；冻结 VLM，只训 DiT action head + robot-state projector；默认单张 24GB GPU；LoRA 可选。
- **数据**：33k 成功演示；按 session/物体/背景分组划分；合成失败（截断/加噪/位移/遮挡）+ 仿真扰动；真实失败少量。
- **目标**：主损失仍是 flow-matching/diffusion action loss；可选加一个“风险/失败”辅助头（同一模型，不是第二个策略），用合成/仿真标签训练；若无可靠标签，不加。
- **恢复数据**：如果 G9 证明重试有效，再用仿真/单任务通道收集“盾干预后的纠正动作”，做 DAgger 式微调；否则不做，避免用噪声数据污染主策略。
- **不做**：不从零训；不在 sim 里追 32 任务成功率；不训第二个残差策略；不用测试集调阈值。


## 4. GUARD：安全盾

### 4.1 运动学/工作空间/自碰撞

- 用 G1 URDF + Dex1 夹爪，取关节限位、速度/加速度/加加速度上限。
- 对每个 EE 目标做 IK；若 IK 无解/超限，投影到最近可行关节目标。
- 工作空间用凸多面体（桌面以上、机器人前方、避开头部/躯干）；越界就裁剪。
- 自碰撞用胶囊体近似：上臂/前臂/手/躯干/头；对插值轨迹采样 10 个点检查。
- 环境障碍用头部双目粗视差/点云；在 5 Hz 下建 2–5 cm 体素栅格，检查扫掠体积。
- 对针管（SyringeWaterTransfer）单独加“尖端限速/限高/远离人脸”规则；对玻璃/陶瓷（ArrangePlates、StackBowls、PaperCupStacking）加“降速/减小夹持冲击”规则。

### 4.2 跟踪误差碰撞检测

没有力/触觉，用“命令 vs 实际”的跟踪误差做碰撞代理：

```math
e_{\mathrm{track}}(t)=\|p_{\mathrm{cmd}}(t-\Delta)-p_{\mathrm{obs}}(t)\|
+\lambda\|R_{\mathrm{cmd}}(t-\Delta)\ominus R_{\mathrm{obs}}(t)\|.
```

- 若 `e_track > θ_track` 连续 `K` 帧，且命令速度非零，判碰撞/卡住。
- `θ_track` 用成功演示的正常跟踪误差分布标定（例如 p99 的 2–3 倍）。
- 注意 evaluator 可能有自己的平滑/限速；阈值要在单任务通道实测，不能直接用 sim 值。
- 跟踪误差也能检测“夹爪夹到桌面/物体卡住”；配合夹爪开口和腕部图，区分碰撞 vs 抓取成功后的正常负载。

### 4.3 人类接近

- 头部双目做视差 → 点云；用运动（帧差）+ 肤色 + 深度做手/人候选；不依赖第二个学习模型。
- 计算人到机器人扫掠体积的最小距离 `d_human`。
- 分级：
  - `d_human > d_safe`：正常；
  - `d_hold < d_human ≤ d_safe`：按 `d_human/d_safe` 降速（软限制）；
  - `d_human ≤ d_hold`：停 + 保持 + 等待人离开；不突然大幅回撤（可能撞到人）。
- 人为干扰轴占 20%；这既是安全，也是成功率。
- 若用预训练检测器，明确它是安全传感器，不参与任务动作决策；优先确定性 CV 以规避单模型争议。

### 4.4 动作平滑与“可信度”

评测端记录动作统计规律；安全盾不能把动作切成锯齿。做法：

- 低通滤波 + jerk 限幅；
- chunk 边界与上一 chunk 最后一步混合（避免跳变）；
- 截断/保持时用平滑过渡，不要瞬间反向；
- 监控动作范数/方差；若异常，回退到安全保持并记录；
- 绝不返回 NaN/inf/错误形状。

### 4.5 安全回撤

预计算一个无碰撞的 home/预抓取位姿 `T_safe`，并预计算一条从常见工作位姿到 `T_safe` 的无碰撞路径。回撤时：

- 先抬升到桌面以上安全高度，再水平移动；
- 速度/加速度限幅；
- 若人进入回撤路径，停在原地等待，不强行穿过；
- 回撤完成后 `reset` 局部状态，准备重试或结束。

### 4.6 合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 安全/失败检测只离线生成标签；线上只有 VLA | 最低 | 保守 |
| C2 确定性控制器 | 安全盾/恢复原语/预算都是几何/控制律，无学习权重；VLA 是唯一学习模型 | 低；需说明 | **主推** |
| C3 同 checkpoint 特征 | 目标描述子用 VLA 同一 checkpoint 的 encoder | 低–中 | 需要强描述子时用 |

禁止：加载第二个学习策略/残差网络/独立视觉编码器做在线任务决策。

## 5. FAIL / RETRY

### 5.1 失败信号

| 失败模式 | 信号 | 判定 | 恢复 |
|---|---|---|---|
| 没夹住 | 夹爪开口 vs 物体宽度；腕部图物体是否在指间；抬头图物体是否仍不动 | 闭合后提升 2 cm，物体未随动 | 回撤 → 重定位 → 重抓 |
| 滑落 | 物体相对夹爪位移；`r_grasp` 突变 | 连续 2–3 帧位移超阈值 | 停 → 降低加速度 → 重抓 |
| 掉落 | 头部图物体向下运动/消失 | 物体落到桌面/桌下 | 若在桌面：重定位重抓；若掉出：abort |
| 碰撞/卡住 | 命令 vs 观测 EE 跟踪误差；关节速度饱和 | 连续 K 步 `e_track > θ` | 停 → 回撤 → 重定位 → 重规划 |
| 目标被移走 | 场景运动无法被机器人动作解释（`edit_score`） | 编辑检测触发 | 停 → 等人离开 → 重定位 → 重规划 |
| 插入偏了 | 伺服误差不下降；接触后位置停滞 | 窗口内误差斜率 ≈ 0 | 回撤 2–3 cm → 重新对齐 → 再插 |
| 时间不够 | 剩余时间 < 预估恢复 + 任务时长 | 预算检查 | 安全 abort |

### 5.2 阈值标定

- **正常分布**：用成功演示回放，统计每个信号的分布；取 p99 的 2–3 倍作为初始阈值。
- **失败分布**：从成功演示合成失败（截断、加噪、物体位移、夹爪偏移、遮挡）+ 仿真注入 + 少量真实失败。
- **工作点**：`FPR ≤5%`、`TPR ≥80%`、检测延迟 `≤200 ms`；每个模式单独报告。
- **在线自适应**：如果连续多次误报，临时放宽阈值/关闭该模式（但不能关闭碰撞检测）；如果连续失败，收紧。
- **不要用测试集调阈值**；按 session/物体/背景分组划分。

### 5.3 重试预算

用 §1.3 的任务时长和 §2.1 的公式，给每个任务算 `N_max`。示例（`T_r=5 s`、`T_i=0.3 s`、`T_s=10 s`）：

| 任务 | `T_t` | `N_max`（估算） | 备注 |
|---|---:|---:|---|
| HangCup | 6.2 s | ~14 | 短，重试 ROI 最高 |
| StackBowls | 10.1 s | ~11 | 短，接触密集 |
| DisconnectEthernet | 10.5 s | ~10 | 短，拔插 |
| ZipUp | 14.1 s | ~8 | 中短，拉链 |
| PlugCharger | 15.1 s | ~8 | 中短，插入 |
| PlugInEthernet | 16.4 s | ~7 | 中短，插入 |
| ToolboxStorage | 37.6 s | ~3 | 长，重试贵 |
| StorePaddle | 34.1 s | ~4 | 长 |
| SpellRobot | 31.2 s | ~4 | 长 |

**注意**：`N_max` 是上界；实际要减去推理/观测/恢复的真实开销，并留 10–20 s 安全余量。若 evaluator 判终局失败，`N_max` 只适用于软失败。

### 5.4 重规划上下文

API 的 `observation.language` 是固定的，策略不能改；但发给 VLA server 的内部 prompt 可以带失败上下文：

```text
base: "hang the cup on the marked spot on the cup rack"
failure_context:
  - "previous grasp missed; cup still on table"
  - "target moved left by ~4 cm"
  - "insertion stalled; retry with smaller lateral offset"
```

实现方式：

- 若 WLA server 支持任务 key/unnorm_key，映射到对应任务；
- 若不支持，用空 prompt + 当前图像 + 失败上下文作为附加 token（如果模型支持）；
- 不要假设 WLA 一定吃自然语言；先在单任务通道验证。

### 5.5 终局 vs 非终局

这是本轮最大的规则不确定性。三种可能：

1. **非终局软失败**：模型可以继续动，180 s 内重试有效 → RETRY 收益最大。
2. **部分终局**：物体掉出工作区/超时/碰撞被 evaluator 判失败 → 只能对“未触发终局”的软失败重试。
3. **完全终局**：evaluator 一旦检测到失败就终止 → RETRY 无效，只能做“预防性安全盾”。

**行动**：单任务通道第一件事就是测这个；在结果出来前，不要把 RETRY 的收益写进提交承诺。

### 5.6 预期收益（C 级）

- 若 10 个短任务各 +10 pp → 全局 `10/32×10=+3.1 pp`；
- 若 16 个任务各 +10 pp → `+5.0 pp`；
- 若 RETRY 只覆盖 5 个任务 → `+1.6 pp`；
- 与 CHUNK-SERVO 的 +4–7 pp 叠加（不同失败桶，部分重叠）→ 保守 +5–9 pp，乐观 +10–14 pp；
- **这不是承诺**；必须用配对 A/B、bootstrap、重复实验验证。320 trials 的 SE≈2.4 pp，+1–2 pp 不能下结论。

## 6. SIM-FAULT：仿真故障注入

### 6.1 黑盒 twin（便宜、任务无关）

```text
真实演示 obs/action 回放
  → 注入延迟 τ ~ U(0,200ms)、抖动、丢包、JPEG 噪声、模糊、遮挡
  → 通过真实 PolicyService（含 GUARD/RETRY）
  → 记录：安全盾触发率、误报、恢复成功、p99、动作规律性
```

优点：不需要 32 任务场景；直接测部署/安全/恢复逻辑；可重复。
缺点：没有物理接触/碰撞；不能验证真实碰撞检测阈值。

### 6.2 物理 twin（贵、只做通用原语）

用 `unitree_sim_isaaclab` 的 G1-29dof-Dex1：

- PickPlace-Cylinder：抓取/放置的通用原语；
- PickPlace-RedBlock：抓取/放置；
- Stack-RgyBlock：叠放/接触；
- Move-Cylinder-Wholebody：移动/全身（可选）。

**没有现成场景**：插入（网线/充电器/试管）、拉链、锁、挂杯；这些要么自建场景，要么只在真机单任务通道验证，不假设 sim 能覆盖。

注入：

- 物体初始位置偏移（位置泛化）；
- 背景纹理/光照变化（背景泛化）；
- 额外障碍物（干扰物泛化）；
- 未见物体（替换几何/颜色/材质）；
- 人手进入/移动物体（人为干扰）；
- 关节跟踪误差/执行延迟（部署故障）。

**不追求**：32 任务 1:1 复刻；不追求 sim 成功率预测真机。

### 6.3 故障矩阵

| 维度 | 取值 | 目的 |
|---|---|---|
| 延迟 | 0/50/100/150/200 ms | 安全盾/伺服稳定性 |
| 抖动 | 0/10/30 ms | p99/动作规律性 |
| 丢包 | 0/1/5% | 降级/保持 |
| 图像噪声 | 高斯/JPEG/模糊/遮挡 | 检测鲁棒性 |
| 物体位移 | 1/3/5/10 cm | 重定位/重试 |
| 人手 | 进入/移动/遮挡 | 安全/恢复 |
| 碰撞 | 桌面/自碰撞/卡住 | 跟踪误差阈值 |
| 任务 | 3 个原语 + 5 个代表任务 | 相对排序 |

每个组合至少 50 次；报告成功率、unsafe event rate、恢复率、检测延迟、p99。

### 6.4 标定与 sim-real gap 预算

| 项 | 允许误差 | 超过后的动作 |
|---|---|---|
| 相机外参 | ≤2 cm/2° | 重新标定；关闭 IBVS |
| 焦距尺度 | ≤10% | 用头双目深度；腕部只做粗对齐 |
| 延迟 | ≤30 ms 估计误差 | 降增益/加 chunk |
| 摩擦 | ±20% | 只做相对排序 |
| 物体质量 | ±20% | 只做相对排序 |
| 夹爪柔顺 | ±20% | 只做相对排序 |
| 目标位姿 | ≤5 mm/2° | 只用腕部目标图 |

### 6.5 指标

- `unsafe event rate`：每 100 次尝试的碰撞/卡死/人机接近事件；
- `false positive rate`：安全盾在正常成功演示上的误触发；
- `recovery rate`：失败后恢复到成功的比例；
- `detection latency`：从失败发生到检测的时间；
- `availability`：服务可用性；
- `p99 latency`；
- `action regularity`：jerk/方差/NaN 率。

## 8. 竞赛策略

### 8.1 任务组合（先验，待单任务通道更新）

```text
priority_t = q_t * Δ_t * r_t / cost_t
```

- `q_t`：失败发生在“可恢复/可重试”区间的比例；
- `Δ_t`：GUARD+RETRY 的条件增益；
- `r_t`：重试预算（由 180 s / 任务时长决定）；
- `cost_t`：工程/评测成本。

先验分档：

- **第一梯队（短 + 接触 + 高重试 ROI）**：HangCup、StackBowls、DisconnectEthernet、ZipUp、PlugCharger、PlugInEthernet。
- **第二梯队（短/中短 + 可恢复）**：FruitCollection、FruitSorting、PlacePhotoFrame、ConveyorSorting、ColorArrangement、PaperCupStacking、Unlock、PackBag、SyringeWaterTransfer、PickOutBatteries、ArrangeTestTubes。
- **第三梯队（长任务，重试预算少）**：ToolboxStorage、StorePaddle、SpellRobot、PackPhone、FoldTowel、OrganizeTools、StoreEarphones、OrganizeStationery、PourOutMedicine、ArrangePlates。
- **观察**：早期感知/抓取就失败、重试也救不回来的任务，不投 GUARD/RETRY，保留 VLA 基线。

### 8.2 单任务通道协议

1. 选 5 个代表任务：HangCup（短/挂）、StackBowls（短/叠）、PlugInEthernet（中短/插）、ZipUp（中短/拉链）、ToolboxStorage（长/锁，防回归）。
2. 每任务 5 次 A/B：`guard+retry off` vs `on`；同一初始条件；记录成功、步骤分、耗时、p99、unsafe、重试次数。
3. **先测规则**：失败后继续动是否被允许？重试是否扣步骤分？超时判定是在 180 s 还是更早？
4. 通过标准：≥3/5 任务 +10 pp；长任务不回归 >5 pp；无 unsafe；p99 不升。
5. 再扫 `action_chunk_size ∈ {5, 8}`；固定后不再改。
6. 最后才跑 32×10 正式评测。

### 8.3 提交节奏

| 阶段 | 时间 | 交付 | 退出条件 |
|---|---:|---|---|
| P0 基线/接口 | 1 周 | WLA + adapter + chunk 8 + 零 pivot + 安全保持 | 单任务通道 1 任务跑通 |
| P1 安全盾 | 1–2 周 | 限幅/工作空间/自碰撞/跟踪误差/人类减速/回撤 | G8 初版 |
| P2 失败/恢复 | 2 周 | 6 类检测 + 回撤/重定位/重抓 + 预算 | G9 初版 |
| P3 仿真风洞 | 1–2 周 | 黑盒 + 物理 twin + 故障矩阵 | G8/G11 |
| P4 单任务 A/B | 1–2 周 | 5 任务配对实验 | G9/G10 |

若只允许一次提交：P0 后先交安全基线（锁“更早提交”tie-break），P5 后再交 GUARD-RETRY 版本；不要用正式 320 trials 做未验证的 A/B。

## 10. 风险与合规

### 10.1 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 安全/失败检测只离线生成标签；线上只有 VLA | 最低 | 保守 |
| C2 确定性控制器 | 安全盾/恢复原语/预算都是几何/控制律；VLA 是唯一学习模型 | 低；需说明 | **主推** |

禁止：加载第二个学习策略/残差网络/独立视觉编码器做在线任务决策。

### 10.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 安全盾误报 | 合法接触被停，成功率下降 | 阈值用成功演示分布标定；软/硬两级；按任务启用 |
| 人类检测漏报 | 人机碰撞风险 | 双目 + 运动 + 深度多信号；保守减速；不声称 100% |
| 重试被判定终局失败 | RETRY 无效 | 先用单任务通道测规则；只对软失败重试 |
| 重试拖超时 | 反而丢分 | 预算公式 + 安全余量 + 主动 abort |
| 步骤分惩罚重试 | tie-break 吃亏 | 记录步骤分；只在成功率优先时启用 |
| 单模型解释 | 被判定第二个模型 | 安全/恢复全为确定性控制器；不加载第二个学习策略；材料写清 |
| 共享模型并发 | 延迟升高/端口串扰 | 请求队列 + 批处理 + 每端口 session；压测 |
| 动作不规律 | 评测端可信度下降 | 平滑/限 jerk/无 NaN；监控动作统计 |
| sim gap | 阈值迁移失败 | 只做相对排序/初值；真机复核；报告 gap |
| 评测噪声 | +1–2 pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4 pp |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |
| `pivot` 语义不一致 | 动作被拒/机器人不动 | 先用 `example_env.py`/单任务通道验证；保留零 pivot 回退 |
| 提交次数限制 | 无法多次 A/B | 邮件确认；单任务通道先验证；一次提交则保守 |

### 10.3 评测噪声

- 320 trials 下 `p≈0.25` 的 SE≈2.4 pp；+1–2 pp 不能下结论。
- 用配对 A/B（同任务/同初始条件）降低方差；报告 bootstrap 95% CI。
- 不要用预览榜单的任务排名做难度表；它是 `gen_leaderboard.py` 生成的。
- 单任务通道 5 次/任务只能看方向，不能看显著性；需要更多重复或配对设计。

|---|---|---|---|---|---|---|
| **I1 GUARD-SHIELD** | 一次碰撞/卡死/人机事故可能丢掉当前 trial，甚至让机器人离线 | 在 VLA 的 action chunk 上做确定性 shielding；不是第二个学习策略 | 高 | G1 URDF、双目、安全盒、单任务通道 | 回放→限幅/工作空间/自碰撞→人类减速→跟踪误差→sim→A/B | 误报降成功率；人类检测漏报 |
| **I2 FAIL-RETRY** | 180 s 对短任务宽裕；非终局失败可恢复 | 确定性恢复原语 + 同一 VLA 重规划 + 预算化重试 | 中高 | 演示关键帧/时长、单任务通道 | 测规则→6 类检测→回撤/重定位/重抓→预算→A/B | 终局失败、超时、步骤分惩罚 |
| **I3 SLO-DEPLOY** | 远程自部署；延迟/端口串扰/NaN 会丢 trial | 把提交当生产服务：异步、隔离、熔断、动作规律性 | 高 | 工程、容器、压测 | run_server→异步 cache→端口隔离→压测→熔断→部署卡片 | 过度工程、共享模型并发 |
| **I4 SIM-FAULT** | 安全/恢复阈值不能拍脑袋；真机不能试碰撞 | sim 只认证控制器，不训策略；黑盒 + 物理 twin | 中高 | IsaacLab、回放、注入脚本 | 黑盒 replay→注入→3 原语→标定→报告 gap | sim gap、场景搭建成本 |
| **I5 FAIL-CORPUS** | 33k 演示全是成功，没有失败样本 | 合成失败 + 重试经济学（任务时长/恢复成本） | 高 | 演示、仿真、统计 | 合成失败→标阈值→算 `N_max`→排序→A/B | 合成/真实分布不一致 |
| **I6 RISK-VLA** | 扩散/流采样可能出坏 chunk | 同一 VLA 多次采样 + 确定性过滤/排序；test-time compute | 中 | GPU 余量、低延迟、候选排序器 | K=2/4→过滤→排序→短任务→看涨点 | 延迟翻倍、多样性不足、合规解释 |

**优先级建议**：I1 + I2 是主投；I3 是低成本的“保命层”；I4/I5 是使能项；I6 是观察项，只有在延迟有余量时才做。
