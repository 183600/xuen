# 第 13 轮（本循环第 1 轮）· OPEN-BRANCH：把「歧义」当成未合并的分支——先执行公共前缀，用双足身体主动消歧，证据够了再提交

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新灵感循环第 1 轮，承接第 10 轮 **FACT-VLA**、第 11 轮 **GEO-RESIDUAL**、第 12 轮 **CHUNK-SERVO**；外部事实沿用第 12 轮已核实的 A 级材料（2026-10-28），并吸收同轮候选档案中 **STANCE-VIEW SEARCH**（pivot 语义、静态 stance 安全集）、**REFER-SERVO**（腕部彩色内参存在）、**DEADLINE-PLAN**（`action_chunk_size` 全局固定、有效运动前缀可调）的三处修正。本轮新增内容除特别标注外均为 **C 级设计假设**，需 G8–G12 验证。

### 0.1 本轮思考轨迹（先给过程）

1. **先回看第 12 轮的三处隐含假设**：目标实例唯一、任务相位唯一、任务帧唯一。CHUNK-SERVO 的 5 步伺服很快，但它默认「参考是对的」；如果参考错了，快只是更快地错。
2. **再查同轮候选档案，避免重复**：STANCE / STANCE-VIEW SEARCH 已经做了「目标出视野/超可达域时重选 stance」；MATE 已经做了「实例对比选择 + margin 拒答」；SILK 已经做了「连续信念状态」；CLAUSE 已经做了「语言契约」；DEADLINE-PLAN 已经做了「固定 chunk + 有效前缀」。这些都很强，但都还停留在「选一个」或「信一个」。
3. **找到缺口**：没有一个方案显式回答「在选之前，哪些动作对多个假设都安全？多个假设能不能共享一个身体 stance？证据到什么程度才允许提交？」这正是开源软件的 fork/merge/CI 能提供的形式：分支、共同祖先、测试、评审、合并、锁文件。
4. **把三个灵感词钉到机制上**：开源软件 → 分支/公共前缀/CI/共形合并；双足机器人 → 平衡相容 stance 交集 + 身体主动消歧 + 步态作为提交边界；多模态大模型 → 假设生成 + 语义评审 + 语言先验。
5. **形式化后再做玩具检查**：用 3 分支蒙特卡洛先验证「延迟提交」的收益和「过度自信」的破坏力；结果支持「分支有价值，但校准是最大风险」，于是把共形覆盖率和 null 分支写成上线前提，而不是事后补丁。

## 0. 先给结论：CHUNK-SERVO 让闭环变快，但没有回答「闭环应该锁在哪个分支上」

第 12 轮把 30 步开环 chunk 改成「30 步规划 + 5 步视觉伺服」，把接触段的反馈周期从约 1 s 压到约 200–320 ms。这是正确的方向。但它仍然默认三个「唯一」：

1. **目标实例唯一**：演示检索到的 `T_target_ee*` 对应当前场景里的正确受器；
2. **任务相位唯一**：当前一定处于某个已知阶段，而不是「可能已经插好」「可能被人拉开」；
3. **任务帧唯一**：孔轴、杯沿、拉链线、锁孔只有一个合理解释。

真实桌面恰好在这三处制造歧义：同类杯子、多个网口/试管位、遮挡、透明、人为移动/撤销。此时更快的伺服只会更快地锁定错误分支。

把一次失败拆开：

```text
P(fail) = P(branch wrong)                 # 选错实例 / 相位 / 任务帧
        + P(frame wrong | branch right)   # 分支对，但接口几何估计错
        + P(control fail | frame right)   # 几何对，但延迟/接触/滑移
```

第 12 轮主要打第三项；第 11 轮打第二项；第一项一直是一个隐含假设。**而歧义恰好是离散的、低维的、可以被显式分支表示的。**

所以本轮的押注是 **OPEN-BRANCH**：

> **用开源软件的 fork/merge/CI 原语组织执行：检测到歧义就分叉出少量假设分支；先执行对所有分支都安全、都不破坏的「公共前缀」；用双足身体的腰/高/小步作为主动消歧传感器；用确定性测试和同一多模态大模型的评审过滤分支；当共形分支集收缩为单例、或 deadline 到达时，才提交给 CHUNK-SERVO 做最后 3 厘米闭环。**

一句话对比第 12 轮：**CHUNK-SERVO 让闭环变快；OPEN-BRANCH 让闭环在歧义下不急于提交。**

三个可验证创新点（不是三个宏大名目）：

1. **分支相容公共前缀（Branch-Compatible Shared Prefix, BCSP）**：在多个假设分支上求「安全 + 不破坏任何分支可行性」的最长公共动作前缀；验证它是否降低选错实例/相位的不可逆动作，而不是只降低碰撞。
2. **平衡相容分支集（Balance-Aware Branch Set, BABS）**：双足机器人的分支不只需要可达，还需要存在公共 stance；当 stance 交集为空时，用腰/高/小步做主动消歧或提交。验证身体动作是否比纯手臂「看一眼」更快、更稳。
3. **共形合并/提交（Merge/Commit with Conformal Risk, MCP）**：用共形预测把「分支集是否可信」变成一个分布无关的覆盖率问题；分支集为单例才提交，否则执行公共前缀/观察动作；验证提交错误率是否被控制在 `α` 附近。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 关键设计 | 不做什么 |
|---|---|---|---|
| **开源软件** | 分支树、公共祖先、CI 测试、评审、合并、锁文件 | fork 出假设分支；公共前缀=动作的共同祖先；安全/可达/平衡/契约测试=CI；同 checkpoint 的 VLM=reviewer；`lockfile` 记录每端口分支状态 | 不把「开源」理解成再加载一个开源模型；不做第二个在线策略；不把 git 当装饰性比喻 |
| **双足机器人** | 平衡相容 stance 集、主动消歧、步态边界 | 分支必须共享支撑多边形内的 stance；腰 yaw/pitch/height 做视差消歧；小步是「提交边界」而非连续行走 | 不做全身 RL；不默认行走；不在接触段动身体；不假设 pivot 语义已完全核实 |
| **多模态大模型** | 假设生成、语义评审、语言先验 | 用同一 WLA checkpoint 的 VLM 生成 2–4 个指代/相位/任务帧假设；用同 checkpoint 的视觉编码器做分支打分；离线用 33k 演示构造歧义校准集 | 不加载第二个检测/分割大模型；不把 VLM 当精确控制器；不在每个 chunk 都调用 VLM |

## 1. 直觉：歧义不是噪声，是「还没合并的分支」

### 1.1 为什么用分支，而不是一个更自信的单一预测

所有 VLA 都输出一个动作块；它没有显式的「我不确定是左边杯子还是右边杯子」的表示，更没有「先做一个对两个杯子都安全的动作，再决定」的机制。于是策略只有两种行为：

- **过早提交**：按最大后验选一个目标，快速伺服过去；如果选错，接触/抓取/放置都可能不可逆。
- **犹豫/抖动**：在多个目标之间来回修正，浪费时间，甚至把两个物体都碰倒。

分支表示把这两个极端变成一个可控的决策问题：

```text
歧义出现 → fork 出 2–4 个分支
         → 能共享的动作先执行（公共前缀）
         → 不能共享时，做一个对所有人都安全的观察动作
         → 证据够了 → merge/commit
         → 证据不够且 deadline 到 → 按风险提交或安全放弃
```

这跟开源软件的工作方式同构：**分支是廉价的，提交是昂贵的；先让多个假设并行存活，用测试和评审决定谁能合并。** 开源软件不是「一个人写出完美程序」，而是「很多分支 + 测试 + 评审 + 合并 + 锁文件」；机器人执行也不应该「一个模型一次猜对」，而应该「少量分支 + 确定性测试 + 多模态评审 + 共形提交」。

### 1.2 为什么歧义是离散的

连续位姿误差（偏了 2 mm）适合用 CHUNK-SERVO / GEO-RESIDUAL；但下面这些歧义是**离散的**，用连续伺服去平均它们是错误的：

| 歧义类型 | 例子 | 为什么离散 |
|---|---|---|
| 指代歧义 | 桌上有两个同款杯子；两个网口 | 目标是「哪一个实例」，不是「实例中心偏了多少」 |
| 相位歧义 | 插头已经插好？拉链已经拉上？人把盖子拧回去了？ | 状态是「完成/未完成/被撤销」，不是连续误差 |
| 任务帧歧义 | 孔轴、杯沿、拉链头、锁孔；透明/反光导致两个解释 | 功能帧是「哪一条轴/哪一个面」，不是位姿微调 |
| 策略歧义 | 先抓柄还是先抓杯身；左手还是右手 | 动作模式是离散选择 |

离散歧义用离散分支；连续误差用伺服。**两者是串联的，不是替代的。**

### 1.3 为什么是双足机器人，而不是固定底座机械臂

固定底座机械臂的分支只受「可达/碰撞」约束；G1 的分支还受**支撑多边形**约束。两个分支如果需要不同的腰/高/底座姿态，它们就不能无限期共存：这就是 **stance merge conflict（姿态合并冲突）**。

这带来三个双足特有的机会：

1. **公共 stance 交集**：如果两个分支都能在同一个 stance 下完成，就保持身体不动，只动手臂；如果交集为空，就必须提交或换 stance。
2. **身体作为主动消歧传感器**：腰 yaw/pitch 几度的变化、身高几厘米的变化，就能让两个同类物体在双目中的投影分离；必要时一个小步（5–15 cm）产生平移视差。这比让手臂在两个目标之间来回试探安全得多。
3. **步态是提交边界**：一旦迈步，支撑多边形变了，之前的「公共 stance」不再成立；所以步态只能发生在分支合并/提交点，不能在每个 chunk 里随意走。

这不是「全身控制当第三只手」的重复；它把身体当成**分支可行性的共享资源**和**消歧动作**。STANCE / STANCE-VIEW SEARCH 已经覆盖了「目标出视野/超可达域时重选 stance」；OPEN-BRANCH 的增量是「多个分支的 stance 交集 + 用身体动作做信息增益 + 步态作为提交边界」。

### 1.4 为什么是多模态大模型，而不是第二个控制器

多模态模型最擅长的不是毫米级控制，而是：

- 把语言 + 图像解析成少量**离散假设**：目标实例、任务相位、功能帧、抓取模式；
- 对这些假设做**语义评审**：这个动作是否还符合指令？这个分支是否已经不可能？
- 在失败后给出**语言诊断**：插头拿反了、杯子在左边、拉链头被布盖住了。

所以 OPEN-BRANCH 让 VLM 做「假设生成 + 评审」，让 VLA action expert 做「动作先验」，让 CHUNK-SERVO 做「最后 3 厘米」，让确定性测试做「CI」。**唯一的学习模型仍然是同一个 checkpoint；分支层没有可训练权重。**

## 2. CHUNK-SERVO 留下了什么，OPEN-BRANCH 补什么

### 2.1 继承

- **FACT-VLA**：相位化行为克隆、CAC 柔顺执行、EGP 证据门控——保留；OPEN-BRANCH 把相位从「唯一状态」升级为「分支变量」。
- **GEO-RESIDUAL**：动作条件化三维残差、米制表面距离、编辑检测——保留；OPEN-BRANCH 把它们当作分支证据和分支测试。
- **CHUNK-SERVO**：30 步规划 + 5 步视觉伺服、演示检索相对目标、数字孪生标定——保留；OPEN-BRANCH 只决定「伺服到哪个目标、什么时候提交」。
- **STANCE-VIEW SEARCH**：pivot 语义、任务级静态 stance 先验、安全集、接触段冻结——保留；OPEN-BRANCH 升级为多分支 stance 交集。
- **MATE**：实例掩码、场景校准对比分数、margin 拒答——保留；OPEN-BRANCH 把「选/拒」升级为「分支/共享前缀/共形提交」。
- **SILK**：信念状态、证据更新——保留；OPEN-BRANCH 把连续信念离散成少量可执行分支。
- **CLAUSE**：语言契约、相位谓词、恢复边——保留；OPEN-BRANCH 用契约定义分支测试和合并条件。
- **DEADLINE-PLAN**：固定 chunk、有效运动前缀、180 s 预算——保留；OPEN-BRANCH 用有效前缀 `k` 和 deadline-aware commit。

### 2.2 增量

| 前任 | 前任回答的问题 | OPEN-BRANCH 新增的问题 |
|---|---|---|
| CHUNK-SERVO | 怎么在 5 步内修正位姿？ | 修正到哪个分支？什么时候可以不再分支？ |
| GEO-RESIDUAL | 场景哪里动了？ | 动了之后应该 fork 出哪些新分支？ |
| FACT-VLA | 当前相位是什么？ | 当前相位是否唯一？如果不唯一，哪些动作对多个相位都安全？ |
| STANCE-VIEW SEARCH | 目标出视野/超可达域时换哪个 stance？ | 多个分支能否共享一个 stance？不能时用身体动作消歧还是提交？ |

### 2.3 明确不重复

- 不重复 STANCE / STANCE-VIEW SEARCH 的「单 stance 重选」；本轮是多分支 stance 交集与主动消歧。
- 不重复 MATE 的「实例对比选择」；本轮是分支保持、公共前缀、共形提交。
- 不重复 SILK 的「连续信念状态」；本轮把信念离散成少量可合并分支。
- 不重复 CLAUSE 的「语言契约」；本轮用契约做分支测试，不重新编译 32 条指令。
- 不重复 TVC / LEDGER 的「任务状态版本控制/回滚」；本轮的分支是**执行前的歧义分支**，不是执行后的回滚账本。

## 3. 形式化草图：分支、公共前缀、平衡相容、共形提交

### 3.1 分支

在时刻 `t`，维护一个有限假设集 `H_t`。每个分支

```text
h = (i, φ, F, g, S_h, A_h)
```

其中：

- `i`：目标实例（或受器/槽位）身份；
- `φ`：任务相位（approach / align / contact / insert / release / recover 等）；
- `F`：任务帧（孔轴、杯沿圆、拉链线、锁孔平面）；
- `g`：该分支的期望夹爪位姿（由演示检索 + 相对目标给出）；
- `S_h`：该分支的可行 stance 集（腰/高/底座，满足 CoM、关节限位、桌面间隙、目标可见、目标可达）；
- `A_h`：该分支的可行动作集（满足运动学、碰撞、平衡、契约）。

信念 `b_t(h)` 由贝叶斯更新：

```text
b_{t+1}(h) ∝ p(o_{t+1} | h, a_t) · b_t(h)
```

证据包括：实例掩码/描述子匹配、重投影误差、深度有效性、夹爪/本体残差、同一 VLM checkpoint 的语义评分。**证据必须校准；这是本方案最大的风险，见 §8。**

### 3.2 公共前缀

给定动作块 `a = (a_1, ..., a_H)` 和提交索引 `k`，前缀 `a_{1:k}` 是公共的，当且仅当

```text
a_{1:k} ∈ ⋂_{h ∈ H_t^+} ( A_h^safe ∩ A_h^compat )
```

- `A_h^safe`：不碰撞、不超关节限位、不破坏平衡、不违反接触契约；
- `A_h^compat`：不破坏分支 `h` 的可行性（例如：如果两个分支是「左杯/右杯」，公共前缀不能先去抓其中一个）。

同时，前缀期间的身体 stance 必须满足

```text
s_{1:k} ∈ ⋂_{h ∈ H_t^+} S_h
```

如果交集为空，就不存在公共前缀；此时只能：

1. 做一个**观察动作**（腰/高/小步），最大化分支间的预期观测差异；
2. 或者提交到最大后验分支；
3. 或者安全 hold / 请求重规划。

### 3.3 共形分支集与提交

设 `s(h, o)` 是分支 `h` 在观测 `o` 下的非一致性分数（越小越可信）。在离线歧义校准集上取 `(1-α)` 分位数 `q̂`，在线定义

```text
H_t^+ = { h : s(h, o_t) ≤ q̂ }
```

在可交换性假设下，`P(h* ∈ H_t^+) ≥ 1-α`。于是：

- **分支集为单例**：提交到该分支，交给 CHUNK-SERVO；
- **分支集多例**：执行公共前缀或观察动作；
- **分支集包含 null 分支**：说明当前假设集可能漏了真实情况，回退 VLA/重规划；
- **deadline 到达**：提交最大后验分支，并记录风险标记。

这比手工 margin 更有原则：**提交错误率由共形覆盖率控制，而不是由拍脑袋的阈值控制。**

### 3.4 目标函数

在每个 chunk 边界，选择动作 `a`：

```text
maximize  Σ_h b(h) · Δ_h(a) + λ · IG(a) - μ · cost(a)
subject to a ∈ A_shared 或 a ∈ A_look
```

- `Δ_h(a)`：分支 `h` 下的预期任务进度；
- `IG(a)`：预期信息增益（分支后验熵的下降）；
- `cost(a)`：时间/能量/风险；
- `A_shared`：公共前缀动作集；
- `A_look`：对所有分支都安全的观察动作集。

这是一个**分支空间上的短视模型预测控制**；不需要完整 POMDP 求解器，只需要在 2–4 个分支、几个候选动作上做枚举。

## 4. 算法总览：三条路径

```text
                         ┌──────────────────────────────┐
                         │  Per-port PolicyService      │
                         │  ├─ branch tree / belief     │
                         │  ├─ shared-prefix compiler   │
                         │  ├─ look-action planner      │
                         │  ├─ CI tests (safety/contract)│
                         │  ├─ VLM reviewer (same ckpt) │
                         │  └─ CHUNK-SERVO executor     │
                         └──────────────┬───────────────┘
                                        │
                         ┌──────────────▼───────────────┐
                         │  Shared WLA server (GPU)     │
                         │  30-step plan + VLM query    │
                         └──────────────────────────────┘
```

每个 `get_action`：

1. **更新分支**：用当前观测更新信念；剪掉低概率分支；必要时 fork 新分支（目标移动、相位被撤销、遮挡消失）。
2. **快速路径**：如果共形分支集是单例，且所有 CI 测试通过 → 直接调用 CHUNK-SERVO，提交到该分支。
3. **分支路径**：如果多例 → 计算公共前缀；如果存在 → 执行公共前缀 + 安全 hold 后缀；如果不存在 → 计算观察动作。
4. **观察路径**：在腰 yaw/pitch/height（必要时小步）的候选集中，选一个对所有分支安全、且最大化预期观测分离的动作；执行后不提交。
5. **兜底**：如果分支集包含 null、或没有安全动作、或 deadline 到达 → 提交最大后验分支或安全 hold；记录锁文件与失败日志。

关键点：**OPEN-BRANCH 不替代 CHUNK-SERVO，而是给它一个「提交后的目标」和「提交前的公共动作」。** 在绝大多数没有歧义的 chunk 上，它退化为 CHUNK-SERVO，不增加开销。

## 5. 三个可验证创新点

### 5.1 BCSP：分支相容公共前缀

**假设**：在同类实例/多受器场景中，大部分接近动作可以在分支间共享；先执行公共前缀，能把「选错实例」的不可逆动作推迟到证据足够时，从而降低错误抓取/错误插入。

**证伪**：如果公共前缀的平均长度 <1 个 chunk，或者执行公共前缀后成功率不升反降（因为浪费时间/错过时机），BCSP 不成立。

**实验**：离线统计 33k 演示中「同任务多实例」的接近段相似度；仿真对比「立即 MAP 提交」vs「公共前缀 + 提交」；真机 2 个任务 A/B。

### 5.2 BABS：平衡相容分支集与身体消歧

**假设**：双足的分支可行性由 stance 交集决定；当交集为空时，一个小的腰/高/步观察动作比手臂来回试探更快、更安全；身体消歧能减少「选错实例」和「接触段破坏」。

**证伪**：如果身体观察动作的消歧时间不优于纯手臂观察，或者平衡裕度下降/接触破坏率上升，BABS 不成立。

**实验**：仿真三任务族（双杯、双网口、拉链相位）；对比「无观察」「手臂观察」「腰观察」「小步观察」；记录 time-to-commit、平衡裕度、碰撞。

### 5.3 MCP：共形合并/提交

**假设**：用手工 margin 提交在不同场景/背景下会漂移；用共形分支集可以把提交错误率控制在 `α` 附近，并在分布漂移时通过自适应共形/分组共形保持保守。

**证伪**：如果离线 ECE >0.15、覆盖率 <80%、或真机提交错误率明显高于 `α`，MCP 不成立。

**实验**：离线歧义校准集（同款物体、遮挡、相位边界）；仿真/真机记录提交错误；对比固定 margin、温度缩放、共形。

## 6. 实验门 G8–G12（新增，不替代 G0–G7）

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| **G8** | 假设生成与校准是否可信？ | 离线 top-3 分支召回 ≥90%；共形覆盖率 ≥90%（α=0.1）；ECE ≤0.10；平均分支集 ≤2.5 | 降低 α/改用几何分支；只在高歧义任务启用 |
| **G9** | 公共前缀是否真的涨点？ | 仿真歧义场景成功率 ≥ MAP 提交 +10pp；错误实例率 ↓≥50%；碰撞/超时不升 | 回退 MAP + CHUNK-SERVO；只保留观察动作 |
| **G10** | 身体消歧是否有效？ | time-to-commit 比纯手臂观察 ↓≥30%；平衡裕度不低于阈值；接触破坏不升 | 只用腰/高，不用小步；或禁用身体观察 |
| **G11** | 真机单任务是否涨点？ | ≥3/5 任务 +10pp 或错误实例率 ↓≥50%；对照任务不回归 >5pp | 不提交 OPEN-BRANCH 版本 |
| **G12** | 全量干跑是否稳定？ | N 端口分支状态隔离；reset 干净；内存不涨；p99 ≤ 基线 +20% | 回退基线；只保留离线分析 |

## 7. 风险与边界

| 风险 | 影响 | 缓解 |
|---|---|---|
| 分支信念校准错误 | 更自信地提交错误分支 | 共形覆盖率、温度缩放、null 分支、保守 α、失败回退 MAP |
| 真实分支不在假设集 | 公共前缀可能对真实情况不安全 | null 分支、开放集检测、假设集不收缩时 hold/look |
| 分支爆炸 | 延迟/算力上升 | 最多 4 个分支；低概率剪枝；只在歧义触发时启用 |
| 公共前缀过于保守 | 超时/错过时机 | deadline-aware commit；允许分支后缀；缩短观察 |
| 身体观察破坏接触/平衡 | 任务失败/摔倒 | 接触段冻结身体；小角度/小步；平衡滤波器 |
| 小步不被 API/评测支持 | 动作被拒/机器人不动 | 默认只用腰/高；G12 先验证 pivot；步态仅作可选 |
| API chunk 固定 | chunk 内不能重新观测 | 有效运动前缀 `k` + 安全 hold 后缀；H 全局固定 |
| VLM 延迟 | p99 上升 | 只在分支点调用；缓存；几何分支兜底 |
| 单模型解释 | 被判定为第二个模型 | 分支层无可训练权重；同一 checkpoint；C1/C2/C3 合规说明 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |

**明确不做**：不从零训 VLA/World Model；不做第二个在线策略/分割大模型；不做完整 POMDP 求解；不做 30Hz 广域网 VLM；不默认行走；不把预览榜单当难度表。

## 8. 一句话押注与一句话风险

**一句话押注：用开源软件的 fork/merge/CI 原语，把 CHUNK-SERVO 的单一参考升级为「少量分支 + 公共前缀 + 双足主动消歧 + 共形提交」；在歧义场景中，宁可晚一个 chunk 提交，也不要把错误实例/相位/任务帧做成不可逆动作。**

**本轮最大风险：如果多模态模型和几何证据给出的分支置信度系统性偏高，OPEN-BRANCH 会把「延迟提交」变成「更自信地提交错误分支」，而且比 CHUNK-SERVO 更难被发现；所以共形校准和 null 分支不是可选项，而是上线前提。**

## 0. 结论与边界

### 0.1 一句话结论

CHUNK-SERVO 把「30 步开环」压成「30 步规划 + 5 步伺服」，但它仍然假设目标实例、任务相位、任务帧三者唯一；OPEN-BRANCH 用少量离散分支表示这三类歧义，先执行对所有分支都安全、都不破坏的公共动作前缀，用双足腰/高/小步做主动消歧，用确定性 CI 测试和同一多模态 checkpoint 做评审，最后用共形分支集决定「何时提交」；在歧义场景中，它把「选错实例/相位/任务帧」的不可逆动作推迟到证据足够时，代价是少量观察时间和一个更难校准的信念层。

| A | 官方文档、提交模板、数据集元数据、官方代码直接核实（沿用第 12 轮及同轮候选复核） | 规则/API、33,276 eps、WLA `chunk_size=30`、pivot 语义、腕部彩色内参、`action_chunk_size` 全局固定 |

### 1.2 三处修正（相对第 12 轮）

1. **腕部彩色内参存在（A，REFER-SERVO 复核）**：32/32 数据集的 `wrist_left.color.camera_matrix` / `wrist_right.color.camera_matrix` 存在（fx≈434–437，fy≈434–437，cx≈317–324，cy≈239–243）。第 12 轮「腕部没有内参」应修正为「API 不暴露 IR/深度，但彩色内参可用于 2D 伺服/重投影」。本方案的分支证据可以使用腕部彩色内参，但仍不能假设腕部深度。

3. **pivot 语义（A，STANCE-VIEW SEARCH 复核）**：官方 WLA action server 把 `action.pivot [7]` 定义为 `[vx, vy, vw, yaw, pitch, roll, height]`，其中 yaw/pitch/roll 来自 waist（`lower_body` 最后 3 维，原顺序 `[yaw, roll, pitch]`，需重排），height 来自 base_command。挑战赛评测端是否完全同语义是 **C**，必须先用小幅 waist/height 指令验证；本方案默认只用腰/高，不默认用 `vx/vy/vw` 行走。

### 1.3 本轮新增的 C 级假设

- 歧义可以被 2–4 个离散分支覆盖；真实分支通常在这几个候选里，漏掉的概率由 null 分支/开放集检测兜底。
- 同一 WLA checkpoint 的 VLM 能给出可用的分支假设和语义评分；如果不可用，几何分支仍可运行，但效果下降。
- 公共前缀在多数接近段存在；如果不存在，观察动作仍比盲目提交安全。
- 双足 stance 交集在多数桌面任务中非空；空集时可以用腰/高观察，小步只在验证后启用。
- 共形校准集与测试场景可交换；分布漂移时用分组/自适应共形保持保守。

### 2.1 基础符号

| 符号 | 含义 |

| `t` | 控制步；`f_c` 控制频率（默认 30 Hz，待实测） |
| `H` | 全局固定的 `action_chunk_size`，候选 `{5, 8}` |
| `k ≤ H` | chunk 内有效运动前缀长度；后 `H-k` 步是安全 hold/制动 |
| `o_t` | 观测：四路 RGB、双臂关节/EE、夹爪、`lower_body`、语言 |
| `ℓ` | 任务语言指令（episode 内固定） |

| `b_t(h)` | 分支后验信念 |
| `A_h^safe` | 分支 `h` 下满足安全约束的动作集 |
| `A_h^compat` | 分支 `h` 下不破坏其可行性的动作集 |
| `S_h` | 分支 `h` 的可行 stance 集 |
| `g_h` | 分支 `h` 的期望夹爪位姿/相对目标 |

| `T_max` | 单次 trial 的剩余时间预算（≤180 s） |

### 2.2 分支定义

定义分支为七元组：

```text
h = (i, φ, F, g, S_h, A_h^safe, A_h^compat)
```

其中：

- `i ∈ I`：目标实例/受器/槽位身份；`I` 可以包含 `null`（表示「以上都不是」）。
- `φ ∈ Φ`：任务相位。沿用 FACT-VLA/CLAUSE 的相位集：`LOCATE, APPROACH, PREGRASP, GRASP, LIFT, TRANSPORT, ALIGN, CONTACT, INSERT, RELEASE, RETREAT, RECOVER`。
- `F`：任务帧，定义在受器局部坐标系上；例如孔轴 `(p, n)`、杯沿圆 `(c, r, n)`、拉链线 `(p, d)`、锁孔平面 `(p, n)`。
- `g`：由演示检索得到的「受器→夹爪」相对目标，或由任务帧解析出的期望 EE 位姿。
- `S_h`：满足 CoM/支撑多边形、关节限位、桌面间隙、目标可见、目标可达的 stance 集。
- `A_h^safe` / `A_h^compat`：动作集；前者是安全，后者是分支可行性。

### 2.3 信念更新

设分支先验为 `b_0(h)`，由任务语言、演示统计和 VLM 先验给出。在线证据 `e_t` 包括：

- 实例掩码/描述子匹配（同一 checkpoint 的视觉编码器或经典描述子）；
- 任务帧重投影误差；
- 双目深度有效性/视差；
- 夹爪开度、EE 速度、关节残差；
- VLM 语义评分（同一 checkpoint）；
- 物理可行性（IK/碰撞/平衡）。

信念更新：

```text
b_{t+1}(h) = p(e_{t+1} | h, a_t) b_t(h) / Σ_{h'} p(e_{t+1} | h', a_t) b_t(h')
```

为了避免证据重复计数，把证据分组做朴素贝叶斯/温度校准；具体校准方法见 §4.1。**信念不是装饰：它决定公共前缀的候选集和提交时机。**

### 2.4 公共前缀

给定动作块 `a = (a_1, ..., a_H)` 和提交索引 `k`，称 `a_{1:k}` 为分支集 `H_t^+` 的**公共前缀**，当且仅当：

```text
(1) a_{1:k} ∈ ⋂_{h ∈ H_t^+} A_h^safe
(2) a_{1:k} ∈ ⋂_{h ∈ H_t^+} A_h^compat
(3) s_{1:k} ∈ ⋂_{h ∈ H_t^+} S_h
```

条件 (1) 是安全；条件 (2) 是「不破坏分支」；条件 (3) 是「身体 stance 对所有分支都可行」。三者缺一不可。

- 条件 (1) 保证不碰撞、不超限、不失衡。
- 条件 (2) 保证不提前抓错/插错/松手；例如两个分支是左杯/右杯，公共前缀可以「移到两杯中间、张开夹爪、保持两杯可见」，但不能「抓住左杯」。
- 条件 (3) 保证双足分支可以共存；如果两个分支需要不同的 stance，交集为空，就不能无限期保持两个分支。

### 2.5 共形分支集

设非一致性分数 `s(h, o) ∈ R`，越小越可信。离线歧义校准集 `{(o_i, h_i*)}` 与测试可交换。取

```text
q̂ = Quantile_{⌈(m+1)(1-α)⌉/m} { s(h_i*, o_i) }
H_t^+ = { h ∈ H_t : s(h, o_t) ≤ q̂ }
```

则在可交换性假设下：

```text
P(h* ∈ H_t^+) ≥ 1 - α
```

如果 `|H_t^+| = 1`，提交到该单例；如果 `|H_t^+| > 1`，保持分支；如果 `null ∈ H_t^+`，回退 VLA/重规划。

**注意**：共形保证的是覆盖率，不是效率。如果 `s` 很差，分支集会一直很大，机器人会一直观察/犹豫；所以还需要好的假设生成和分支打分，共形只负责「不把错误分支排除掉」。

### 2.6 目标函数与约束

在每个 chunk 边界，选择动作 `a` 和提交索引 `k`：

```text
maximize   Σ_{h ∈ H_t^+} b_t(h) · Δ_h(a)  +  λ · IG(a)  -  μ · cost(a)
subject to a ∈ A_shared(k) ∪ A_look
           k ≤ H
           T_remaining ≥ T_exec(a) + T_safe
```

- `Δ_h(a)`：分支 `h` 下的预期任务进度（0–1），可由伺服误差/相位谓词/演示进度估计。
- `IG(a)`：预期信息增益，见 §4.3。
- `cost(a)`：时间、能量、风险、与演示的偏离。
- `A_shared(k)`：长度为 `k` 的公共前缀集合。
- `A_look`：对所有分支都安全的观察动作集合。
- `T_safe`：安全余量（例如 2 s）。

这是一个短视（myopic）版本；如果需要，可以对 `k` 做 1–2 步 lookahead，但不做完整 POMDP。

## 3. 算法步骤与伪代码

### 3.1 进程/端口拓扑

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)       │
                    │  ├─ branch tree / belief            │
                    │  ├─ shared-prefix compiler          │
                    │  ├─ look-action planner             │
                    │  ├─ CI tests (safe/compat/balance)  │
                    │  ├─ VLM reviewer (same checkpoint)  │
                    │  ├─ CHUNK-SERVO executor            │
                    │  └─ lockfile / failure log          │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared WLA server (GPU)            │
                    │  30-step plan + VLM query           │
                    └─────────────────────────────────────┘
```

- 每个端口独立 `BranchState`：分支树、信念、已提交分支、锁文件、失败日志。
- 共享 WLA server 只提供同一 checkpoint 的 30 步 plan 和 VLM 查询；不共享端口状态。
- 分支层是 CPU 线程，不阻塞 websocket；VLM 查询异步、可缓存、可超时。

### 3.2 `get_action` 主循环

```python
class OpenBranchPolicy:
    def get_action(self, obs):
        self.t += 1
        self._update_belief(obs)
        self._maybe_fork(obs)

        # 0) deadline / null branch / no safe action -> fallback
        if self._must_fallback(obs):
            return self._fallback(obs)

        # 1) fast path: conformal singleton and CI passes
        if len(self.H_plus) == 1:
            h = next(iter(self.H_plus))
            if self._ci_pass(h, self._branch_plan(h, obs)):
                self._commit(h)
                return self.chunk_servo.get_action(obs, goal=h.g)

        # 2) branch path: shared prefix
        k, a_shared = self._shared_prefix(obs)
        if k >= 1:
            a_cmd = self._fill_safe_hold(a_shared, H=self.H, k=k)
            self._log_shared(k, a_shared)
            return self.adapter.to_api(a_cmd, obs)

        # 3) look path: body/arm observation that is safe for all branches
        a_look = self._look_action(obs)
        if a_look is not None:
            self._log_look(a_look)
            return self.adapter.to_api(a_look, obs)

        # 4) last resort: commit MAP with risk flag or hold
        return self._commit_map_or_hold(obs)
```

### 3.3 信念更新与分支维护

```python
def _update_belief(self, obs):
    for h in self.branches:
        e = self._evidence(h, obs)          # mask/frame/depth/proprio/VLM
        self.logp[h] += self._log_likelihood(e, h)
    self.b = softmax(self.logp)
    # prune branches with b < eps_b, but keep null and at least 2 if ambiguous
    self.branches = self._prune(self.branches, self.b, eps_b=0.02)
    self.H_plus = self._conformal_set(self.branches, obs)

def _maybe_fork(self, obs):
    # fork when ambiguity score high, or edit/target-move detected
    if self._ambiguity(self.b) > tau_a or self._edit_detected(obs):
        new = self._vlm_hypotheses(obs)      # same checkpoint, 2-4 branches
        self.branches = self._merge_duplicates(self.branches + new)
        self.logp = self._reprioritize(self.logp, new)
```

### 3.4 公共前缀编译器

```python
def _shared_prefix(self, obs):
    # 1) get branch-specific goals/plans from demo retrieval + servo
    plans = {h: self._branch_plan(h, obs) for h in self.H_plus}

    # 2) find longest prefix where all plans are close and safe/compat
    best_k, best_a = 0, None
    for k in range(1, self.H + 1):
        a = self._neutral_prefix(plans, k, obs)   # medoid/VLA prior projected
        if a is None:
            break
        if all(self._ci_pass(h, a, prefix=True) for h in self.H_plus):
            best_k, best_a = k, a
        else:
            break
    return best_k, best_a

def _neutral_prefix(self, plans, k, obs):
    # candidate: VLA 30-step plan prefix, branch-plan medoid, or neutral pre-grasp
    cands = [self.vla_plan[:k]] + [plans[h][:k] for h in plans]
    cands.append(self._neutral_pregrasp(k, obs))
    for a in cands:
        if a is not None and all(self._prefix_close(a, plans[h][:k], eps_a)
                                 for h in plans):
            return a
    return None
```

关键细节：**不能直接用 VLA plan 当公共前缀**，因为 VLA 可能已经隐含选择了某个分支。必须检查它是否对所有分支 `compat`；如果不满足，改用中性预抓取或分支计划的 medoid。

### 3.5 CI 测试

```python
def _ci_pass(self, h, a, prefix=False):
    return (
        self._kinematic_ok(h, a)      # IK/joint limits/reach
        and self._collision_ok(h, a)  # swept volume vs table/objects/self
        and self._balance_ok(h, a)    # CoM/capture point in support polygon
        and self._contract_ok(h, a)   # phase pre/postconditions
        and self._budget_ok(a)        # remaining 180 s
    )
```

每个测试返回布尔值和置信度；任一硬约束失败即拒绝。软约束（语义评审）作为排序分数，不作为硬门。

### 3.6 观察动作

```python
def _look_action(self, obs):
    # candidates: waist yaw/pitch/height, optional small step
    cands = self._stance_candidates(obs)      # ~5x5x3 grid
    best, best_score = None, -inf
    for s in cands:
        if not self._stance_safe_for_all(s):  # balance + table + visibility
            continue
        score = self._expected_separation(s)  # min pairwise predicted projection
        score += 0.3 * self._expected_visibility(s)
        score -= 0.2 * self._motion_cost(s)
        if score > best_score:
            best, best_score = s, score
    if best is None:
        return None
    return self._stance_to_chunk(best, H=self.H, hold_suffix=True)
```

`_expected_separation` 用当前各分支的目标点/任务帧在候选 stance 下的预测投影，取分支间最小像素/米制分离；这是主动感知的近似信息增益。

### 3.7 合并与提交

```python
def _merge_commit(self, obs):
    # 1) merge branches that share the same action suffix
    merged = self._merge_by_suffix(self.H_plus)
    if len(merged) == 1:
        self._commit(merged[0])
        return self.chunk_servo.get_action(obs, goal=merged[0].g)

    # 2) if two branches are observationally equivalent but different goals,
    #    keep them; choose a look action or shared prefix.
    if self._deadline_reached(obs):
        h = self._map_branch(merged)
        self._commit(h, risk="deadline")
        return self.chunk_servo.get_action(obs, goal=h.g)

    return None
```

### 3.8 与 CHUNK-SERVO 的接口

CHUNK-SERVO 的 `get_action(obs, goal)` 负责：

- 30 步 VLA plan 缓存；
- 5 步执行块；
- 相对目标 `goal.g` 的 IBVS/PBVS 修正；
- 接触段法向缩幅；
- 延迟补偿。

OPEN-BRANCH 只做三件事：

1. 决定 `goal` 是哪个分支的 `g_h`；
2. 决定当前 chunk 是「公共前缀 + hold」还是「提交后的伺服」；
3. 决定何时从分支路径切到快速路径。

**如果 OPEN-BRANCH 失效，CHUNK-SERVO 仍在**：分支层只返回合法动作；任何异常回退到 `goal = MAP branch` 或安全 hold。

### 3.9 锁文件与端口隔离

每个端口维护：

```yaml

calibration: {head_stereo: ..., wrist: ..., pivot: ...}
index_version: ...
```

`reset()` 清空分支树、信念、锁文件中的 episode 状态；共享索引/模型只读。**不同端口之间不共享分支状态**，避免 `reset()` 串扰。

## 4. 推导、复杂度与正确性

### 4.1 共形覆盖率与提交风险

设校准集 `{(o_i, h_i*)}` 与测试样本可交换，非一致性分数 `s(h,o)` 固定。定义 `q̂` 为 `s(h_i*, o_i)` 的 `⌈(m+1)(1-α)⌉/m` 分位数，`H^+(o) = {h: s(h,o) ≤ q̂}`。标准 split conformal 给出：

```text
P(h* ∈ H^+(o)) ≥ 1 - α
```

因此，如果只在 `|H^+| = 1` 时提交，则

```text
P(commit wrong) ≤ P(h* ∉ H^+) ≤ α
```

这是一个**分布无关**的有限样本界（在可交换性下）。它不保证任务成功，只保证「提交的分支不是真实分支」的概率受控。

**边界**：

- 如果真实分支不在候选集 `H_t` 中，覆盖率保证不适用；用 `null` 分支和开放集检测兜底。
- 如果测试分布与校准分布不可交换（新背景/新物体/新光照），覆盖率可能下降；用分组共形（按任务/泛化轴）或自适应共形（ACI）保持保守。
- 共形保证覆盖率，不保证分支集小；如果 `s` 很差，机器人会一直观察。假设生成和分支打分仍然重要。

### 4.2 公共前缀安全性

设 `S` 是安全谓词（无碰撞、关节限位、平衡裕度、接触契约），`A_h^safe = {a: S(a,h)=true}`。设 `H_t^+` 是共形分支集，`a_{1:k}` 满足

```text
a_{1:k} ∈ ⋂_{h ∈ H_t^+} A_h^safe
```

若真实分支 `h* ∈ H_t^+`，则 `a_{1:k} ∈ A_{h*}^safe`，即执行前缀满足真实分支的安全约束。结合共形覆盖率：

```text
P(prefix unsafe due to branch miss) ≤ P(h* ∉ H_t^+) ≤ α
```

**假设**：安全谓词精确、低层控制器能跟踪、状态估计误差在标定范围内。若这些假设不成立，界不成立；这是工程风险，不是数学问题。

**注意**：公共前缀的 `compat` 条件不是安全约束；即使 `h*` 被漏掉，前缀可能仍然安全，但可能破坏真实分支的任务可行性。因此 `null` 分支和开放集检测很重要。

### 4.3 观察动作的信息增益

对离散分支和候选观察 `a`，定义

```text
IG(a) = H(b_t) - E_{o' ~ p(o'|b_t,a)} H(b_{t+1}(o'))
      = I(H; O' | a)
```

其中 `I` 是互信息。对二分支情形，设先验 `b = P(h_1)`，观察 `o∈{0,1}` 的似然为 `p(o|h_1)`、`p(o|h_2)`，则

```text
IG(a) = Σ_o P(o) Σ_h P(h|o) log( P(h|o) / P(h) )
```

选择 `a* = argmax_{a∈A_look} IG(a)` 是在候选集上的一步最优熵下降；它不是全局最优任务价值，但计算便宜、可解释。

在实现中，我们不直接估计完整似然，而用**预测投影分离度**近似：

```text
IG(a) ≈ min_{h ≠ h'} || π_h(a) - π_{h'}(a) ||²
```

其中 `π_h(a)` 是分支 `h` 的目标点在候选 stance/动作下的预测像素/米制位置。这个近似偏好「让两个分支在图像上分开」的观察动作，与主动感知的经典做法一致。

### 4.4 公共前缀的占优条件

**命题（共同前缀弱占优）**：假设对每个分支 `h`，其最优动作序列 `π_h` 的前 `k` 步相同，且这些前缀对所有分支安全/相容；则「先执行这 `k` 步公共前缀，再根据新观测重新决策」不会比「在 `t=0` 立即提交到某个分支」更差（在期望任务价值意义下，忽略观察成本）。

**证明思路**：两条策略在前 `k` 步执行完全相同的动作，因此到达同一状态分布；延迟决策的策略在 `k` 步后拥有至少与立即提交策略相同的信息，且可以选择与立即提交策略相同的分支。因此它的可行动作集包含立即提交策略的后续动作，期望价值不低于后者。**前提**是前缀确实相同；如果前缀是折中/中性动作，占优不成立，必须用实验验证。

这个命题解释了为什么公共前缀是「免费期权」：只要分支在接近段确实共享动作，延迟提交没有额外动作成本，只增加了信息。

### 4.5 复杂度与延迟

设：

- `N_h ≤ 4`：分支数；
- `N_a ≤ 8`：候选动作数；
- `N_s ≤ 75`：stance 候选（5 yaw × 5 pitch × 3 height）；
- `H ≤ 8`：chunk 长度；
- `d ≤ 30`：状态维度；
- `C_IK ≈ 0.2 ms`，`C_coll ≈ 0.5 ms`，`C_bal ≈ 0.1 ms`，`C_contract ≈ 0.1 ms`。

复杂度：

| 步骤 | 复杂度 | 估算 |
|---|---|---|
| 信念更新 | `O(N_h N_e)` | `4×6`，<0.1 ms |
| CI 测试 | `O(N_h (C_IK+C_coll+C_bal+C_contract))` | `4×0.9 ms`，≈3.6 ms |
| 公共前缀 | `O(N_h N_a H d)` | `4×8×8×30`，<0.5 ms |
| 观察搜索 | `O(N_s N_h²)` | `75×16`，<1 ms |
| 合并/提交 | `O(N_h H)` | 忽略 |
| VLM 查询 | `O(1)`，100–300 ms | 仅分支点，摊销到 30 步 plan |

**结论**：分支层 CPU 开销 <10 ms/chunk；瓶颈是 VLM 查询。若 VLM p99 超过预算，改用几何分支打分（经典描述子 + 重投影 + 深度），VLM 只在任务开始/失败恢复时调用。

**延迟预算**：`T_fb ≈ H/f_c + τ`。`H=5, f_c=30, τ=100 ms` → 267 ms；`H=8` → 367 ms。分支观察额外增加 1–3 个 chunk（0.17–0.9 s）+ VLM（0.1–0.3 s），相对 6–38 s 的任务时长可接受；但在 180 s 边缘任务上要设 deadline。

### 4.6 平衡与 stance 交集

CoM：

```text
c(q) = Σ_i m_i p_i(q) / Σ_i m_i
```

静态稳定：

```text
c_xy(q) ∈ P(q) ⊖ ε_p
```

其中 `P(q)` 是足底支撑多边形。若可估计 base 速度，用捕获点：

```text
ξ = c_xy + ċ_xy / ω_0,   ω_0 = sqrt(g / h_CoM)
ξ ∈ P(q) ⊖ ε_p
```

分支 stance 集：

```text
S_h = { s : c(s) ∈ P(s) ⊖ ε_p,
            q(s) ∈ [q_min, q_max],
            d(s, T) ≥ d_safe,
            target i_h visible,
            goal g_h reachable }
```

公共 stance：

```text
S_shared = ⋂_{h ∈ H_t^+} S_h
```

若 `S_shared = ∅`，分支 stance 冲突。处理顺序：

1. 先在当前 stance 下做手臂/腕部观察（不改变支撑多边形）；
2. 若观察不足，提交到 MAP 分支并切换到其 stance；
3. 若目标超可达/遮挡且 MAP 分支也不可行，考虑小步（5–15 cm）；小步是提交边界，执行后所有分支必须重锚定。

**安全前提**：低层 WBC 能跟踪 pivot/height；腰/高变化不破坏桌面接触；小步只在 G12 验证后启用。

## 5. 先导分析：玩具 Monte Carlo（B 级，非真机结果）

### 5.1 目的

在写代码前，先用一个极简模型回答两个问题：

1. 「先观察再提交」相对「立即提交」能带来多少收益？
2. 如果分支置信度校准错了（过度自信），收益会损失多少？

这不是机器人实验，不证明 OPEN-BRANCH 在 UniBot 上有效；它只用于校准设计直觉和风险排序。

### 5.2 设定

- 3 个离散分支，真实分支均匀随机。
- 每次观察的正确率 0.8（错误时在另外两个分支中均匀）。
- 信念用精确贝叶斯更新；分支测试完美；成功 = 提交到真实分支。
- 策略：
  - `no_look`：立即提交 MAP；
  - `one_look`：观察一次后提交；
  - `adaptive`：观察直到最大后验 ≥ `1-α` 或达到 `T_max`，然后提交；
  - `overconfident`：在决策时把信念温度设为 0.5（过度自信）；
  - `underconfident`：温度设为 1.5（过度保守）。
- 100,000 次独立 episode；随机种子固定。

### 5.3 结果

| 策略 | α | T_max | 温度 | 成功率 | 平均观察次数 |
|---|---:|---:|---:|---:|---:|
| no_look | – | – | – | **0.334** | 0.00 |
| one_look | – | – | – | **0.800** | 1.00 |
| adaptive | 0.10 | 3 | 1.0 | 0.912 | 2.34 |
| adaptive | 0.10 | 6 | 1.0 | **0.962** | 2.89 |
| adaptive | 0.05 | 6 | 1.0 | 0.964 | 2.89 |
| adaptive | 0.02 | 6 | 1.0 | 0.974 | 3.83 |
| overconfident | 0.10 | 6 | 0.5 | **0.799** | 1.00 |
| overconfident | 0.10 | 6 | 0.7 | 0.799 | 1.00 |
| underconfident | 0.10 | 6 | 1.5 | **0.975** | 3.83 |
| underconfident | 0.10 | 6 | 2.0 | 0.975 | 4.21 |

### 5.4 读法

1. **观察有价值**：从 33.4% 到 80.0%（一次观察），再到 96.2%（自适应观察），说明「延迟提交」在歧义下可能比「立即 MAP」高很多。
2. **过度自信会吃掉收益**：温度 0.5 时，机器人只观察一次就提交，成功率回落到 79.9%，与「一次观察」相同，丢掉了 16.3pp 的自适应收益。这正是本轮最大的风险。
3. **过度保守的代价是时间**：温度 1.5 时成功率高 1.3pp，但平均观察次数从 2.89 增到 3.83；在 180 s 预算下，时间可能比 1.3pp 更值钱。
4. **共形/校准不是可选项**：如果分支置信度不可信，分支层会变成「更优雅地早提交错误分支」。

### 5.5 局限

- 只有 3 个分支、独立观察、完美测试；真实系统的观察相关、测试有误差、控制会失败。
- 成功被简化为「提交正确分支」；真实任务还有抓取/插入/放置失败。
- 观察成本被简化为次数；真实观察可能涉及身体运动、接触破坏、平衡风险。
- 因此，上表只支持「校准很重要」这个定性结论，不支持任何真机涨点承诺。

## 6. 实验设计

### 6.1 离线：歧义基准与共形校准

**数据构造**（只用 33k 成功演示 + 官方任务描述；不引入新模型）：

1. **指代歧义**：对每个任务，找同类实例（同款杯子/试管/积木/盒子/端口）；同一 episode 内交换目标标签，构造 `(左/右)` 两个分支；原始目标为真分支。
2. **受器歧义**：多个槽位/端口/杯架位置；用演示中的目标受器作为真分支。
3. **相位歧义**：取相位边界前后 5–10 帧，用夹爪开度/EE 速度/动作标签确定相位；构造「已完成/未完成」两个分支。
4. **遮挡/背景**：用图像编辑/遮挡块/背景替换构造分布外样本；真分支不变。
5. **人为干扰**：用官方 human_1/human_4 备注的先验，在仿真里构造「移动/拿走/撤销」；离线没有真实 human 视频，所以这一项主要靠仿真。

**指标**：

- 分支 top-1/top-3 召回；
- 共形覆盖率（α=0.1）与平均分支集大小；
- ECE / NLL（校准）；
- 提交错误率（在 `|H^+|=1` 时）；
- 公共前缀平均长度（帧/chunk）；
- 观察动作的预期分离度。

**门 G8**：top-3 召回 ≥90%；覆盖率 ≥90%；ECE ≤0.10；平均分支集 ≤2.5；否则降低 α、改用几何分支或只在高歧义任务启用。

### 6.2 仿真：分支决策风洞

**平台**：G1 URDF + Dex1；MuJoCo 或 IsaacLab；30 Hz；chunk 执行；RTT 注入 0/50/100/150 ms。

**任务族**：

1. **双杯挂杯**：桌上有两个同款杯子，一个在杯架附近，一个在干扰位置；指令「挂杯子」。
2. **双网口插线**：两个网口，一个可用、一个被占用/损坏；指令「插网线」。
3. **拉链相位**：拉链初始半开/全开；人在中途拉开；指令「拉上拉链」。
4. **双堆叠碗**：两个碗堆，指令「叠碗」；测试顺序/目标歧义。

**条件**：

- `MAP + CHUNK-SERVO`（基线）；
- `OPEN-BRANCH`（公共前缀 + 共形提交）；
- `OPEN-BRANCH w/o body look`（只用手臂观察）；
- `OPEN-BRANCH w/o shared prefix`（直接提交 MAP）；
- `OPEN-BRANCH w/o conformal`（固定 margin）；
- `Oracle branch`（上界）。

**指标**：成功率、错误实例率、碰撞率、平衡裕度违规率、time-to-commit、观察次数、p99、超时率。

**门 G9**：OPEN-BRANCH 成功率 ≥ MAP +10pp；错误实例率 ↓≥50%；碰撞/超时不升；否则回退 MAP 或只保留观察动作。

**门 G10**：身体观察的 time-to-commit 比纯手臂观察 ↓≥30%；平衡裕度不低于阈值；接触破坏不升；否则只用腰/高或禁用身体观察。

### 6.3 真机单任务 A/B

**任务**（单任务不计分通道）：

1. HangCup（双杯/干扰杯）；
2. PlugInEthernet（双端口/占用端口）；
3. ZipUp（人中途拉开）；
4. StackBowls（双堆叠目标）；
5. FoldTowel（对照，非歧义/变形任务，防回归）。

**设计**：

- 每任务先 5 次 A/B（MAP vs OPEN-BRANCH），配对初始条件；若方向明确，扩到 10 次。
- 记录成功、错误实例、time-to-commit、观察次数、p99、碰撞/平衡违规。
- 统计：配对差值 + bootstrap 95% CI；5 次/任务只能看方向，不能做显著性声明。
- **门 G11**：≥3/5 任务 +10pp 或错误实例率 ↓≥50%；FoldTowel 不回归 >5pp；否则不提交 OPEN-BRANCH 版本。

### 6.4 全量干跑

- 32 任务 ×10，N 端口，`reset()` 隔离，锁文件/分支树每端口独立。
- 指标：总平均成功率、步骤分、p99、timeout、内存、端口串扰、锁文件一致性。
- **门 G12**：无端口串扰；reset 干净；内存不涨；p99 ≤ 基线 +20%；否则回退基线。

### 6.5 消融

| 消融 | 问题 |
|---|---|
| MAP vs 分支 | 分支本身是否有效？ |
| 公共前缀 vs 直接提交 | 延迟提交是否真的有用？ |
| 身体观察 vs 手臂观察 vs 无观察 | 双足主动消歧是否有效？ |
| 共形 vs 固定 margin vs 温度缩放 | 校准方法是否影响提交错误？ |
| VLM 假设 vs 纯几何假设 | 多模态模型是否值得调用？ |
| 接触锁 on/off | 身体观察是否破坏接触？ |
| `H=5` vs `H=8` | 全局 chunk 大小与 p99 的折中 |
| 小步 on/off | 步态是否安全/有效？（仅仿真/验证后） |

### 6.6 统计与功效

- 320 trials 下，`p≈0.25` 的单次标准误约 `sqrt(0.25×0.75/320)=2.42pp`；按任务聚类后设计效应约 1.9–2.5，总体 SE 约 3.5–4.1pp。
- 每任务 10 次，单任务成功率标准误约 13.7pp；配对设计可降低方差，但仍不能把 +1–2pp 当结论。
- 预注册主指标：歧义任务成功率；次指标：错误实例率、time-to-commit、p99。
- 多重比较：按任务/门分层，报告 bootstrap CI；不做「挑一个任务显著」的声明。

## 7. 竞赛策略：先打歧义，再谈分支

### 7.1 任务分层

| 层级 | 任务特征 | 例子 | 策略 |
|---|---|---|---|
| **A：分支优先** | 多同类实例、多受器/槽位、相位易被撤销 | HangCup、PlugInEthernet、PlugCharger、ArrangeTestTubes、StackBowls、StackCups、Unlock、ZipUp、PackPhone、StoreEarphones、OrganizePencilCase | OPEN-BRANCH + 单任务 A/B |
| **B：触发启用** | 偶发遮挡/干扰/多目标 | FruitSorting、ColorArrangement、OrganizeTools、ToolboxStorage、PlacePhotoFrame | 默认 CHUNK-SERVO；歧义触发分支 |
| **C：不启用** | 单目标、变形、长程语义 | FoldTowel、PackDoll、SpellRobot、ConveyorSorting | 保留 CHUNK-SERVO/VLA，避免分支开销 |

这张表是先验，不是实测难度；A 层任务用演示统计（同类实例数、受器数、相位边界密度）和官方任务描述排序，单任务通道后再更新。

### 7.2 收益算术

- 假设 10–12 个 A 层任务，每个 +10pp → `10/32×10=3.1pp` 到 `12/32×10=3.75pp`。
- 人为干扰轴占 20%；如果分支恢复把 human 轴 +10pp → `+2pp`。
- 合计设计目标 **+5pp** 左右；乐观 +8pp；但必须用 G11 的配对 A/B 证明，不能把 +1–2pp 当结论。
- 成本：每个歧义 episode 多 1–3 个观察 chunk（0.2–0.9 s）+ VLM 0.1–0.3 s；相对 6–38 s 的任务时长可接受；180 s 边缘任务设 deadline。

### 7.3 提交节奏

1. **W0**：CHUNK-SERVO + 官方 WLA 基线；单任务通道确认接口/`pivot`/`H`/token。
2. **W1**：离线歧义基准 + 共形校准；G8。
3. **W2–W3**：仿真分支风洞；G9/G10；确定 `H`、`α`、观察动作集。
4. **W4**：真机单任务 A/B；G11；不通过就不提交分支版本。
5. **W5**：全量干跑；G12；锁文件/端口隔离/p99。
6. **W6**：最终提交；保留 `branch_enabled=false` 的回滚开关。

若只允许一次提交：G11 不过就不上分支版本；CHUNK-SERVO 基线仍是安全选择。

## 8. 已知风险与合规

### 8.1 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 分支信念校准错误 | 更自信地提交错误分支 | 共形覆盖率、温度缩放、null 分支、保守 α、失败回退 MAP |
| 真实分支不在假设集 | 公共前缀可能破坏真实分支 | null 分支、开放集检测、假设集不收缩时 hold/look |
| 共形集一直很大 | 观察过多、超时 | 改进分支打分；deadline-aware commit；分组共形；允许 MAP+risk |
| 分支爆炸 | CPU/p99 上升 | 最多 4 个分支；低概率剪枝；只在歧义触发 |
| 公共前缀过于保守 | 浪费时间/错过接触时机 | 允许分支后缀；缩短观察；deadline |
| 身体观察破坏接触 | 物体被推走/掉落 | 接触锁；接触段只用腕部小观察或 hold |
| 身体观察影响平衡 | 失稳/摔倒 | CoM/捕获点滤波；小角度；低速；支撑多边形检查 |
| 小步不被支持/不安全 | 动作被拒/碰撞 | 默认关闭；G12 先验证；只作为提交边界 |
| VLM 延迟 | p99 上升 | 只分支点调用；缓存；几何分支兜底 |
| VLM 语义错误 | 分支先验错 | 不把 VLM 当唯一证据；几何/本体交叉验证；共形 |
| API chunk 固定 | chunk 内不能重观测 | 有效前缀 `k` + hold 后缀；H 全局固定 |
| 单模型解释 | 被判定第二个模型 | 分支层无可训练权重；同一 checkpoint；C1/C2/C3 说明 |
| 评测噪声 | 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |
| 仿真到真机差距 | 仿真排序不迁移 | 仿真只做相对比较/风洞；真机单任务校准 |

### 8.2 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 分支假设/相位/任务帧由离线演示和规则生成；线上只有 VLA + 确定性分支测试 | 最低 | 保守首选 |
| C2 确定性控制器 | 分支层是几何/控制/统计，无学习权重；VLA 是唯一学习模型 | 低 | 主推 |
| C3 同 checkpoint 特征 | 分支打分用 VLA/VLM 同一 checkpoint 的编码器；不加载第二个模型 | 低–中 | 需要语义分支时用 |

禁止：加载第二个学习策略/残差网络/独立分割大模型做在线决策；把 VLM 的语义评分当成唯一安全证书。

### 8.3 安全与运行时

- 任何分支特定动作必须先过 CI 测试；不过则 hold/look。
- 接触段冻结身体（腰/高/步）；只允许腕部小观察或 hold。
- 分支集包含 null 或没有安全动作 → 回退 VLA/重规划；不硬做。
- 最大观察次数/最大重试次数；deadline 到达提交 MAP 或安全放弃。
- 所有输出做形状/NaN/限幅检查；异常返回上一组合法 chunk 或安全 hold。
- 每端口独立状态；`reset()` 清空分支树/信念/锁文件；共享索引只读。

## 10. 一句话押注与一句话风险

**一句话押注：用开源软件的 fork/merge/CI 原语，把 CHUNK-SERVO 的单一参考升级为「2–4 个分支 + 公共前缀 + 双足主动消歧 + 共形提交」；在歧义场景中，宁可晚一个 chunk 提交，也不要把错误实例/相位/任务帧做成不可逆动作。**

**本轮最大风险：如果多模态模型和几何证据给出的分支置信度系统性偏高，OPEN-BRANCH 会把「延迟提交」变成「更自信地提交错误分支」，而且比 CHUNK-SERVO 更难被发现；共形校准和 null 分支必须作为上线前提，而不是事后补丁。**
