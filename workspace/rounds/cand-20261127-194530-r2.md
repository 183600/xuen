## 1. 直觉与动机（两个灵感的碰撞）

### 灵感 1（具身智能大模型 → 它是考官，不是考生）
直觉：6B 的 UnifoLM-WLA/ER（F23）在 15Hz、单卡 24GB、N 端口的在线预算里是奢侈品；但它在**离线**是极好的「考官」：它能读懂任务、能看视频判断「瓶盖拧开了吗/药倒进盒子了吗/拉链拉上了吗」、能诊断失败模式。我们不需要它在线出动作，只需要它在线下出**判断**——里程碑是否达成、卡在哪、下一步该做什么。判断是低维的，比动作更容易蒸馏进一个小头；而官方恰好是**得分点制**（F17/F21），判断直接对齐计分。
严谨定义：设离线大模型为 E，帧 x_t 与指令 u 下 E 给出里程碑后验 q_t∈Δ^K 与失败模式后验 d_t∈Δ^F。用冻结 VLM 特征 f_t 训练轻量学生 h_φ(f_t) 拟合 (q_t,d_t)；在线只跑 h_φ（<1ms），E 永不在线。策略 π_θ 以 h_φ 的输出做辅助监督与恢复条件。核心反直觉点：**大模型的价值不在「替你想动作」，而在「替你判分」——判分比动作便宜一个数量级，却直接命中步骤分。**

### 灵感 2（情感语音 → 没有音频，就迁移它的功能内核）
直觉：本赛观测里没有音频（F18 复核），照搬「情感语音」是伪需求。但情感语音在 HRI 里真正承载的不是「情绪标签」，而是**副语言结构**：重音（哪个词是重点）、顺序（先做什么后做什么）、语气（多急/多谨慎）、确定性（必须/尽量）。这些功能在文本指令里以**语用标记**出现：多子句顺序、连接词、空间副词（从右到左、最上面）、数量词（所有、第一个）、否定/约束（不要掉）、以及「并/再」构成的偏序。F22 的指令正是这种结构。于是我们把「情感语音」迁移为「指令语用 → 任务程序」：把一句话编译成带偏序的里程碑 DAG + 一个节奏/风险向量，而不是当成一个扁平的任务标签。
严谨定义：语用解析是一个映射 P: u ↦ (O, A, ≺, C, ρ)，其中 O 为指称物体集、A 为动作谓词集、≺ 为偏序（先/后/同时/从…到…）、C 为约束（数量、空间、否定）、ρ 为节奏-风险向量（急/稳/轻）。任务程序是 (A,≺) 的偏序展开；ρ 只调制 chunk 长度、速度与验证强度。核心反直觉点：**「情感」在操作任务里的可计算替身是「约束与节奏」——它不改变目标，只改变执行的谨慎度与顺序。**

### 统一命题：从「成功率」到「步骤分」的重新定位
具身大模型回答「怎么知道做到了哪一步」（离线判分/诊断），情感语音的可迁移内核回答「任务本来分几步、每步的约束是什么」（指令→程序）。二者共同服务于一个目标函数：**在失败集上把部分进度做上去**。这也解释了为什么本轮不新增在线大模块：分数洼地在「失败集的部分进度」，而它的监督信号恰好可以由离线大模型 + 指令程序廉价地造出来。第 2 轮的「数据引擎」结论在本轮升级为：**数据引擎的下一层是「判分引擎」——先能自动判分，才能自动造恢复数据、自动做步骤分消融。**

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2 · 判分引擎版）

> 检索日期：2026-11-27；承接第 2 轮 v1.1（I1–I9）。本轮主题：**从「成功率」转向「步骤分」——先把失败集的部分进度做上去。** 三条硬约束不变：单卡 24GB 默认（F25）、15Hz/66ms 量级（F12）、单服务边界（PR2）。来源见 §6；清单只增改不重置。

## 0. 核心决策：分数结构决定优化目标

### 0.1 排行榜拆解（F20，2026-11-27 实测）

设成功率 s、失败集平均步骤分 p，总步骤分 M = 100s + (1-s)p（假设成功集拿满 100）。由公开榜单反推：

| 排名 | 模型/用户 | 成功率 s | 步骤分 M | 反推失败集均值 p |
|---|---|---|---|---|
| 1 | MolmoAct/DexHacker | 29.7% | 39.0 | **13.2** |
| 2 | WALLOSS/Generalist Robotics | 28.5% | 38.9 | 14.6 |
| 3 | DreamZero/World Model Lab | 27.9% | 37.9 | 13.9 |
| 4 | spirit/VLAGO | 25.9% | 34.4 | 11.5 |
| 5 | DM/Embodied AI Institute | 23.5% | 31.7 | 10.7 |
| 6 | PI/RoboReasoner | 22.8% | 30.6 | 10.1 |
| 7 | GigaBrain/xembody | 22.6% | 29.5 | 8.9 |
| 8 | gr00t/Humanoid Dynamics | 20.5% | 28.1 | 9.6 |

**读法**：榜首与第 8 名的差距，既有成功率（+9.2pp），也有失败集进度（+3.6 分）。更关键的是绝对水位——**失败 episode 平均只拿到 9–15/100**。多步任务（倒药、收纳文具袋、锁工具箱）的失败往往发生在最后一步，理论上应从 13 抬到 20+。

**敏感性**：若成功集实际只拿 90/95 分，则榜首 p 分别升到 17.5/15.3；结论「失败集进度很低、是可操作杠杆」不变。

### 0.2 分数杠杆表（榜首处线性近似）

∂M/∂s = 100−p ≈ 86.8，∂M/∂p = 1−s ≈ 0.703。因此：

| 目标总分增量 | 需要成功率增量 | 或需要失败集平均进度增量 |
|---|---|---|
| +1.0 | +1.15pp | +1.42 |
| +3.0 | +3.46pp | +4.27 |
| +5.0 | +5.76pp | +7.11 |

**决策**：在 30% 成功率前沿，+5.8pp 成功率极难；把失败集从 13 抬到 20（+7）同样约 +4.9 分，且失败样本占 70%，数据量充足、监督可造。**本轮主攻后者，成功率作为约束（不得回退）。**

### 0.3 为什么是「判分引擎」而不是「更大的策略」

官方得分点制（F17/F21）+ 公开榜单（F20）意味着：**步骤分是可直接监督的稠密信号**，但官方只给总分、不给每帧里程碑标签。6B 具身大模型（F23）在离线恰好能补这个标签；把它蒸馏成 <1ms 的进度头，在线成本几乎为零。**先能自动判分，才能自动造恢复数据、自动做步骤分消融**——这是本轮所有新想法的共同基础设施。

## 1. 创新点清单（每点：动机 / 与现有差异 / 技术可行性 / 资源 / 落地 / 风险）

### I10 具身大模型离线诊断教师 ★★★★★（新）

- **动机**：步骤分优化的瓶颈不是策略容量，而是**没有每帧「做到哪一步」的标签**。官方 32k 演示只有成功轨迹与任务级指令（F21/F22），失败集的部分进度无监督。6B EFM 能看视频判断里程碑与失败模式，但绝不能在线跑（预算不符）。
- **与现有差异**：v1.1 的 I5 用「手工脚本原语 + 自造里程碑」；I10 把判分本身交给大模型离线完成，再蒸馏成轻量学生。与「动作蒸馏」不同，这里蒸馏的是**低维判断**（K 个里程碑 + F 个失败模式），容量需求小、可解释、直接对齐计分。
- **方法**：
  1. **里程碑逆向**：LLM/EFM 读任务描述 + wiki + 示例，提出每任务 K 个里程碑及视觉证据（如 PourOutMedicine：接近瓶→抓盖→拧开→抓瓶→倾倒→复位）；人工校对 32 张「里程碑卡」。
  2. **帧级标注**：EFM 对每帧给里程碑后验 q_t；用**单调 Viterbi/动态规划**强制进度不回退，得到 q_t*；失败 episode 再由 EFM 输出失败模式 d_t（抓偏/错物/碰撞/遮挡/卡住）。
  3. **蒸馏**：冻结 VLM 特征 f_t（F25 的 `vl_hidden_dim`），训练轻量头 h_φ(f_t) 拟合 (q_t*, d_t)；辅助损失 + 里程碑条件的 BC/恢复损失。
  4. **在线**：只跑 h_φ（<1ms）；EFM 永不在线。h_φ 输出作为 I5 恢复条件、I12 课程权重、I8 消融指标。
- **计分轴**：全局步骤分，优先多步任务（PourOutMedicine、OrganizePencilCase、ToolboxStorage、PlugCharger、ZipUp）。
- **技术可行性**：中-高。EFM 权重已开源（F23）；单调 DP 与蒸馏均为成熟技术；难点在里程碑定义与官方得分点对齐。
- **所需资源**：EFM 离线推理 1×A100 80G（或 24GB 4-bit）× 2 GPU 日（每 5 帧采样）；进度头 1×24GB × 1 日；人工 32 任务 × 10 分钟定义 + 5% 帧抽检。
- **落地步骤**：①逆向 3 个多步任务得分点；②EFM 标注 + 人工 κ 校验；③蒸馏进度头；④接 I5/I12；⑤L0 相关性 + L1 真机。
- **风险**：EFM 幻觉里程碑 / 与官方得分点错位（缓解：人工里程碑卡 + 只保留 κ≥0.8 的任务；PR6 判分先行）；单调 DP 掩盖真实回退（缓解：保留 d_t 的失败模式，不强行单调化失败诊断）；标注成本（缓解：5 帧采样 + 主动学习选帧）。

### I11 指令语用 → 任务程序 ★★★（新，条件性）

- **动机**：F22 的指令是**多子句、带顺序/空间/数量约束**的「程序」，不是扁平标签。情感语音在本赛无音频通道，但其功能内核（重音/顺序/语气/确定性）恰好对应这些语用结构。
- **与现有差异**：现有方案把 `observation.language` 直接喂 VLM 当条件；I11 先把它编译成显式偏序 DAG + 约束集 + 节奏向量，作为辅助监督与 reset 先验。
- **方法**：
  1. **语用解析** P(u) = (O, A, ≺, C, ρ)：分词/子句切分 → 动作谓词与物体指称 → 顺序（先/再/并/从…到…）→ 约束（所有/第一个/最上面/不要掉）→ 节奏（急/稳/轻，若无标记则 default）。
  2. **任务程序**：把 (A,≺) 展开为里程碑 DAG，与 I10 的里程碑卡对齐；每个节点即一个二值里程碑。
  3. **用法**：①辅助监督（子目标/顺序标签）；②reset 期先验（子目标顺序、数量约束）；③与 I9 检索结合（检索「该里程碑对应的技能段」）。
  4. **语言增广**：同义改写/语序变换/加入干扰物/否定，测语言鲁棒性；仅在确认评测指令会变化时放量。
- **计分轴**：多步任务的步骤分；语言泛化轴（若评测变指令）。
- **技术可行性**：中。规则 + 小模型即可；32 条指令可先手工校对。
- **所需资源**：1 人周；无额外 GPU 推理（reset 期 <50ms）。
- **落地步骤**：①32 条指令解析 + 人工校对；②与 I10 里程碑对齐；③作为辅助标签训练；④验证指令固定时的增量；⑤决定是否合并进 I10。
- **风险**：**若评测指令固定不变，I11 的语言泛化价值≈0**（缓解：先核实评测协议；价值退化为里程碑结构，合并进 I10）；解析错误（缓解：程序只作软辅助，不硬约束；raw instruction 始终保留）；节奏向量无官方标注（缓解：默认安全，不依赖）。

### I12 步骤分目标与里程碑课程 ★★★★（新）

- **动机**：BC 只监督成功轨迹的完整动作，失败集的部分进度没有梯度。若能从「已达成的里程碑」中途重启并只学「到下一里程碑」的短段，等于把长程任务拆成多个短程子任务，直接提升失败集进度。
- **与现有差异**：v1.1 的 I5 是「扰动重放/跨段缝合」；I12 是**按里程碑切分的课程**，切点由 I10 判分器给出，目标函数显式加权「里程碑增益」。
- **方法**：
  1. **Resume-from-milestone**：对每条成功演示，找到里程碑 k 首次达成的帧 t_k；构造样本 (obs_{t_k}, 剩余程序 k+1..K) → 监督后续段。模型学会「从中间态继续」，而非只会从初始态开始。
  2. **部分信用目标**：L = L_BC + λ·L_prog + μ·L_gain，其中 L_gain 奖励「本 chunk 内里程碑进度增量」；仅用演示/合成成功段，避免自奖励 hack。
  3. **失败课程**：用 I10 诊断的失败模式，优先采样「差最后一步」的失败段做恢复训练（与 I5 v3 共用管线）。
  4. **可选过滤式 RL/DPO**：只在离线合成段上做偏好过滤，不上在线 RL（合规红线）。
- **计分轴**：全局步骤分；尤其多步任务。
- **技术可行性**：中。数据工程为主；切点质量依赖 I10。
- **所需资源**：1×24GB × 2–3 日；数据工程 1–2 人周。
- **落地步骤**：①3 任务试点；②resume 样本构造 + 质量门禁（必须到达下一里程碑）；③与 BC 基线对照；④L0 步骤分代理；⑤L1 真机。
- **风险**：切点错误导致「剩余程序」与初始态不匹配（缓解：I10 置信门控 + 人工抽检）；课程偏置使模型只会「续做」不会「从头做」（缓解：混合原始完整轨迹，比例 ≥50%）；部分信用目标被 hack（缓解：只用成功段监督，不用自生成奖励）。

### I5 v3 非标称示教合成 + 得分点对齐恢复（深化，优先级↑）

- **本轮变化**：从「先合成再标注」改为「先诊断再合成」——I10 判出失败卡点后，只合成「最后里程碑 → 下一里程碑」的短段；合成段必须被 I10 判为「推进了里程碑」才保留。恢复不再依赖手工原语。

### 2.1 离线判分与蒸馏（I10）

```python
# 离线：6B EFM 当考官（每 5 帧采样）
MILESTONES = {task: build_milestone_card(task_desc, wiki, examples) for task in TASKS}

def label_episode(EFM, frames, task):
    q = [EFM.milestone_posterior(f, MILESTONES[task]) for f in frames]   # (T, K)
    q = monotone_viterbi(q)                                               # 进度单调约束
    last = int(q[-1].argmax())
    fail = EFM.failure_mode(frames, MILESTONES[task]) if last < K - 1 else None
    return q, last, fail

# 训练轻量学生：冻结 VLM 特征 f_t（F25）
head = ProgressHead(in_dim=2560, K=K, F=len(FAIL_MODES))
for batch in demos:

    loss += aux_milestone_bc(policy, f_t, q_t)   # 里程碑条件 BC
```

### 2.2 指令语用解析（I11）

```python
def parse_pragmatics(u):
    clauses = split_clauses(u, seps=["，", "。", "并", "再", "然后", "先"])
    A = [extract_action(c) for c in clauses]
    O = [extract_referent(c) for c in clauses]
    prec = extract_order(clauses)              # 偏序：先/后/同时/从…到…
    C = extract_constraints(u)                 # 所有/第一个/最上面/不要掉
    rho = extract_pace(u, default="safe")      # 急/稳/轻；无标记=default
    return Program(actions=A, objects=O, order=prec, constraints=C, pace=rho)

# 与 I10 里程碑对齐后，作为辅助标签/ reset 先验
program = parse_pragmatics(instruction)
milestones = align(program, MILESTONES[task])
```

### 2.3 里程碑课程（I12）

```python
def build_curriculum(demos, head, K):
    for ep in demos:
        q, last, _ = head.label(ep)
        for k in range(K - 1):
            t_k = first_frame_where(q >= k)          # 里程碑 k 首次达成
            seg = ep[t_k:]
            if head.reaches(seg, k + 1):             # 质量门禁
                yield Sample(obs=seg.frames[0],
                             instruction=remaining_program(k + 1),
                             actions=seg.actions)

# 目标：完整轨迹 ≥50% + 续做课程 ≤50%，防止只会续做
L = L_BC_full + L_BC_resume + λ * L_prog
```
