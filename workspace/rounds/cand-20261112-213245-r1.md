# 第 1 轮（灵感循环 v2：「排行榜」×「容错控制」）—— 从「重试」升级为「分数保持型容错控制」

> **承接与定位**：上一份 v1 已完成的赛制校正（选手 = 远程 `observation→action` API 提交者，不接触执行层）继续有效，本轮不重复论证。v1 的 UIP-01（滚动重试）与 UIP-09（干扰恢复）被**吸收并一般化**为「分数保持型容错控制（SP-FTC）」；UIP-02/03/06/07/08 作为可复用组件保留。为避免编号冲突，本轮新点使用 **UFT = UniBot Fault-Tolerant**，产物区给出与 UIP 的映射。

## 0. 直觉先行（Intuition）

**直觉 A：排行榜是一个「下尾游戏」。** 在成功率偏低、且按「平均成功率 + 步骤分」排序的赛制里，单个任务的得分分布是「大量 0/低分 + 一条部分分长尾」。对这种分布，名次对**下尾**（把 0 分救成部分分）比对**中位数**（把 25% 提到 28%）更敏感。容错控制的原义恰是「故障下维持可接受性能」；在这里「可接受」=「不丢掉已经挣到的步骤分」。所以两者天然合流：**容错控制 = 排行榜下的分数保险**。

**直觉 B：容错控制有两根杠杆，我们只能拉「决策」端。** 被动容错（把策略做得更抗扰、动作更平滑、多视图冗余）与主动容错（检测→诊断→重构→降级）。我们无权改电机/实时控制器，但完全能在 `get_action` 内实现：残差监测、专家/控制空间切换、重抓原语、安全停靠。

**直觉 C：可信度是「第三种故障」。** 评测用逐步延迟及其波动、动作统计规律性判断结果可信度。一次「抖动式抢救」本身就是新故障。因此容错策略必须**自身可信**：有硬延迟预算、动作 C¹ 连续、统计特征贴近标称。

**直觉 D：检测不是越多越好。** 在分数目标下，误报有真实成本（多余重规划、动作跳变、超时）。所以该优化的是**检测器的分数工作点**，不是 AUC 或召回率——这是与常规异常检测研究最反直觉的分歧。

## 1. 严谨定义（Definitions）

### 1.1 计分模型与故障模型
- 任务 \(i\)，计分步 \(j\in J_i\)，权重 \(w_{ij}\ge 0\)，\(\sum_j w_{ij}=100\)。回合得分 \(S_i=\sum_j w_{ij}\,\mathbf 1[j\text{ 达成}]\)（可撤销性见 §1.4）。
- 复合榜分（官方公式未公开，故参数化）：\(R=\alpha\cdot \frac1{32}\sum_i \mathbf 1[\text{success}_i]+(1-\alpha)\cdot \frac1{32}\sum_i S_i/100\)；后文对 \(\alpha\) 做敏感性分析，不押注单一公式。
- 故障算子 \(f\) 作用在观测/转移/动作通道：\(o'=\phi_o^f(o)\)，\(s'=\phi_s^f(s,a)\)。故障集 \(F=\{\text{感知退化、语义误配、策略漂移、执行失败、接口异常、人为干扰}\}\)。
- 故障调度为 \(F\) 上的随机过程；一条轨迹对应一个任务 epoch。

### 1.2 分数保持型容错（SP-FTC）
策略 \(\pi\) 在故障分布 \(P_F\) 下是 \((\varepsilon,\delta)\)-分数保持容错的，若
\[
P_F\!\left[S_i(\pi;f)\ \ge\ (1-\varepsilon)\,S_i(\pi;\text{nominal})\right]\ \ge 1-\delta,
\]
且同时满足可信度约束 \(P[\text{latency}>L_{\max}]\le \delta_\ell\)、平滑度 \(D_{\text{smooth}}\le D_{\max}\)。**容错的对象是得分，不是成功；约束是可信度，不是算力。**

### 1.3 分数账本、分数保持集、可恢复度
- 账本 \(L_t\)：已达成计分步及权重，\(S_t=\sum_{j\in L_t}w_{ij}\)。
- 分数保持集 \(\mathcal P_i=\{s:\text{从 }s\text{ 执行兜底 }\pi_{\text{safe}}\text{ 后 }S_t\text{ 不减}\}\)。
- 可恢复度 \(\rho(s)=\Pr[\text{在重构库下回到 }\mathcal P_i]\)；风险暴露 \(=(1-\rho)\,S_t\)，它决定「值不值得主动抢救」。

### 1.4 两种计分制（本轮最关键的未核实项）
- **单调制**：一旦达成即记分、不撤销 → 「停靠」很便宜，FTC 收益最大。
- **终态制**：结束时物体须在目标位才记分 → 「停靠」必须变成「保持」，FTC 是维持而非冻结。
两者的最优策略完全不同，必须从飞书规则手册核实。

### 1.5 主动容错的成本-收益判据
只在
\[
\mathbb E[\Delta S\mid f]\ >\ \lambda_t\,\mathbb E[\Delta t]+\lambda_s\,D_{\text{smooth}}+\lambda_c\,P(\text{cred flag})
\]
时触发主动重构；否则走被动包络。这把 FTC 从「检测最大化」改写为「带可信度约束的期望分数最大化」。

## 2. 两个灵感词的合流

- **排行榜**：给出目标函数与风险偏好——重下尾、重方差、重可信度，且名次是序数而非基数。
- **容错控制**：给出实现结构——被动包络 + 残差监测 + 故障隔离 + 重构 + 降级。
- **合流命题**：在低成功率 \(+\) 步骤分的榜制下，**「保住部分分」的边际排名收益可能高于「抬高成功率」**；而实现前者最自然、最省样本的框架就是容错控制。定量见 §3。

## 3. 瓶颈假设与边际收益算术

令成功拿满 100、失败的条件均分为 \(s\)，则 \(R(p,s)=100p+(1-p)s\)。取 \(p=0.25,\ s=40\)（工作假设，待榜单校准），\(R=55\)。
- 灵敏度：\(\partial R/\partial p=100-s=60\)（即每 +1pp 成功约 +0.6 榜分）；\(\partial R/\partial s=1-p=0.75\)（即失败部分分每 +1 分约 +0.75 榜分）。
- 于是：失败部分分 \(+10\) → \(+7.5\)；成功率 \(+10\text{pp}\) → \(+6.0\)；成功率 \(+5\text{pp}\) → \(+3.0\)。
- 若 30% 的失败是 0 分，把其中 1/3 救到 30 分：约 \(+3.0\)，且同时压低方差、对序数榜更有利。

结论：**同等实现难度下，抬「失败部分分」的榜分杠杆高于抬成功率**。这是本轮押注 FTC 的定量理由，不是定性口号；若真实分布使 \(s\) 已很高，则杠杆反转，需重新评估。

其他假设：
- 32 任务异质性大，故障类型分布不同 → 容错资源应按任务配置（组合优化）。
- 真机不可反复试 → 必须先有**故障注入回放**，否则 FTC 无法迭代。
- 可信度检查会惩罚「异常动作/异常延迟」→ 主动重构必须限频、限幅、限时。

## 5. 旗舰点的直觉

UFT-01 不追求「检测所有故障」，而追求「在**可能丢分**的故障上，用**最便宜、最平滑**的干预把分保住」。它的默认状态是**被动包络**（低方差、无检测延迟），只在风险暴露高到值得时切**主动重构**。这既符合排行榜的方差厌恶，也避开「抢救动作被可信度判为异常」的陷阱。

## 6. 本轮最大风险（一句话）

## 1. 形式化：把容错写成「受约束的分数最大化」

给定标称策略 \(\pi_0\)、故障算子族 \(\{\phi^f\}_{f\in F}\)、计分函数 \(S(\tau)\)。SP-FTC 求解
\[
\max_{\pi\in\Pi_{\text{API}}}\ \operatorname{CVaR}_{\beta}\!\big[S(\pi)\big]
\quad\text{s.t.}\quad
P[\text{latency}>L_{\max}]\le\delta_\ell,\ \
D_{\text{smooth}}(\pi)\le D_{\max}.
\]
其中 \(\Pi_{\text{API}}\) 是所有可在 `get_action` 内实现、且不触碰执行层的策略。

- 用 \(\operatorname{CVaR}\) 而非均值：名次是序数、且赛制明确会做可信度剔除，**下尾即排名**。取 \(\beta\in[0.1,0.3]\) 关注最差 10%–30% 的回合；也可用 \(\lambda\cdot\mathbb E[S]+(1-\lambda)\cdot\mathrm{CVaR}_\beta[S]\)。
- 约束不可违反：任何提高 \(\mathrm{CVaR}\) 但抬高延迟尾部或动作抖动方差的干预都视为**净负**。

**故障注入的算子定义**（用于离线构造 \(F\)）：
\[
\phi_{\text{occ}},\ \phi_{\text{bg}},\ \phi_{\text{blur}},\ \phi_{\text{dropout}},
\ \phi_{\text{distractor}},\ \phi_{\text{unseen}},\ \phi_{\text{slip}},\ \phi_{\text{delay}},\ \phi_{\text{nan}}.
\]
每条回放轨迹可叠加一个故障调度 \(\sigma\sim\Sigma\)，得到 \((o_{0:T},a_{0:T},S)\) 三元组。

## 2. 故障分类学 → 残差证据 → 处置矩阵

| 故障类 | 可观测残差/证据（廉价优先） | 隔离判据 | 被动包络 | 主动重构 | 主要丢分点 |
|---|---|---|---|---|---|
| 感知-遮挡/模糊 | 时序动作残差 \(\|a_t-a_{t-1}\|\) 突增；跨视图重投影不一致 | 视觉置信骤降但本体正常 | 降速、依赖腕部近景 | 切腕部视图、重观测 | 抓空、碰撞 |
| 语义-未见物/歧义 | VLM grounding 置信低；目标检测缺失/多义 | 语言-视觉匹配失败 | 保守接近、张开夹爪探索 | 重解析指令、候选排序 | 抓错物 |
| 策略-漂移/振荡 | 相邻 chunk 差异大；动作幅值/频率异常 | 残差持续偏高（非瞬时） | 限幅、低增益 | 切专家 / 切控制空间 | 抖振、越界 |
| 执行-滑脱/倾倒 | 物体位姿或光流突变；夹爪闭合后物体位移 | 动作已执行但状态未推进 | 轻放、退出接触 | 重抓/换抓点/抬起重试 | 步骤丢分 |
| 接口-延迟/字段 | 响应时延、NaN、shape/长度不符、缺字段 | 直接校验失败 | 返回保持动作/上一条安全动作 | 预取、降级到轻量头 | 超时、空转 |
| 人为干扰 | 人体/新物体入镜；大面积遮挡 | 场景结构突变 | 安全停、保持姿态 | 等待清场后重规划 | 中断、碰撞 |

**设计原则**：残差先用**解析冗余**（立体+双腕四视图一致性、动作时序一致性）算，不依赖昂贵模型；VLM 只做二级确认。这样默认路径几乎零额外延迟。

## 3. 旗舰 UFT-01 架构

```
                  诊断：故障类 + 置信度
                         │
                         ▼

                         │                 │
                  不通过 │                 │ 通过
                         ▼                 ▼
                   被动包络          主动重构库 r1..r7
                         │                 │
                         └────► 平滑混合 + 延迟预算 ──► action
```

**重构库**（按代价从低到高）：
`r1 重观测`、`r2 改 k 重分块`、`r3 切专家`、`r4 切控制空间`、`r5 慢速重抓原语`、`r6 分数停靠/维持`、`r7 等待清场`。
每个动作附三元代价 \((\Delta S_{\text{期望}},\ \Delta t,\ D_{\text{smooth}})\)，由回放离线标定。

**分数停靠（r6）的两种实现**：
- 单调制：验证已达计分步 → 稳定物体（轻放/保持）→ 结束；
- 终态制：不仅要稳住，还要**维持终态构型**直到 episode 结束 → 用低增益保持控制器，禁止探索性动作。

## 4. 伪代码

```python
class ScorePreservingFTC:
    def __init__(self, nominal, monitors, diagnose, recon, cfg):
        self.nominal = nominal          # 滚动时域策略（v1 UIP-01）
        self.monitors = monitors        # tier1 廉价 / tier2 VLM
        self.diagnose = diagnose        # 残差 -> (fault_class, conf)
        self.recon = recon              # 重构库 + 离线标定代价
        self.cfg = cfg
        self.reset()

    def reset(self):
        self.nominal.reset()
        self.prev_obs = None
        self.prev_act = None
        self.t = 0
        self.health = "nominal"
        self.cooldown = 0               # 限制主动重构频率，防抖动
        self.ledger = []                # 已达成计分步（由进度验证器更新）

    def get_action(self, obs):
        # 1) 健康监测：Tier-1 常态运行；Tier-2 定时或可疑时运行
        res = self.monitors.tier1(obs, self.prev_obs, self.prev_act)
        if res.suspicious or self.monitors.tier2_due(self.t):
            res = self.monitors.tier2(obs, self.lang, self.ledger, res)

        fault, conf = self.diagnose(res)

        # 2) 默认：被动包络（低方差、无检测延迟代价）
        act = self.nominal.get_action(obs)

        # 3) 主动重构：仅在期望收益 > 代价且未冷却时
        if fault is not None and self.cooldown == 0 and conf >= self.cfg.conf_thr:
            exposure = self.risk_exposure(fault, conf)      # (1-rho) * banked_score
            gain = self.recon.expected_gain(fault, exposure)
            cost = self.recon.cost(fault)                   # latency + smoothness + cred
            if gain > cost and self.within_deadline():
                act = self.recon.apply(fault, obs, act)
                self.cooldown = self.cfg.cooldown_steps

        # 4) 平滑护栏：重构不得造成动作跳变
        act = self.smooth(act, self.prev_act)

        self.prev_obs, self.prev_act = obs, act
        self.t += 1
        self.cooldown = max(0, self.cooldown - 1)
        return act

    def risk_exposure(self, fault, conf):
        rho = self.recon.recoverability(fault)   # 离线故障注入标定
        banked = sum(self.w[self.task][j] for j in self.ledger)
        return (1.0 - rho) * banked * conf

    def smooth(self, act, prev):
        if prev is None or not self.cfg.smooth_on:
            return act
        # 短时混合 + 限幅/限速；保持动作统计规律性
        return self.cfg.beta * act + (1 - self.cfg.beta) * prev
```

**三重护栏（本轮的版本）**：
1. `cooldown` + `gain > cost`：限制主动重构的频率与误触发；
2. `within_deadline()`：任何监测/重构都必须落在每步延迟预算内（分级监测）；
3. `smooth()`：重构动作与标称流短时混合，避免可信度判为异常。

## 5. 核心理论点：优化检测器的「分数工作点」，而非 AUC

设故障先验 \(\pi_1=P(f)\)，检测器阈值 \(\theta\) 给出 \(\mathrm{TPR}(\theta),\mathrm{FPR}(\theta)\)。主动干预的期望分数变化
\[
\mathbb E[\Delta S](\theta)=
\pi_1\!\left[\mathrm{TPR}(\theta)\,g-(1-\mathrm{TPR}(\theta))\,\ell\right]
-\pi_0\,\mathrm{FPR}(\theta)\,c ,
\]
其中 \(g\) 为救回分数、\(\ell\) 为错误干预造成的损失、\(c\) 为误报代价（延迟/平滑/可信度）。
**最优阈值 \(\theta^\*\) 最大化上式，而不是最大化 AUC。** 当可信度代价 \(c\) 增大时，\(\theta^\*\) 向高精度端移动；极端情况下最优解是「全被动」（不检测、只做鲁棒包络）。这解释了为什么「更强的异常检测器」未必提高榜分。

## 7. 排行榜策略：跨任务的风险组合（UFT-07）

- 对任务 \(i\) 估计边际价值 \(v_i=\partial\,\mathbb E[\text{rank}]/\partial R_i\)（由分数分布密度近似：低分簇中单位分数更值钱）。
- 给定容错预算 \(B\)（工程时间/推理算力/延迟），解 0-1 背包：选干预 \(k\) 使 \(\sum v_i\,\Delta R_{ik}\) 最大，\(\sum c_{ik}\le B\)。
- **防公共榜过拟合**：用未公开泛化轴的**最坏情况**而非当前公开榜均值做 \(v_i\)；任何干预须过「无回归门」（nominal 分数下降不超过 \(\varepsilon\)）。
- **序数风险**：优先降低方差与 0 分率，而不是追逐单任务峰值；这是低成功率榜制下更稳的占优策略。

## 9. 本轮最大风险（一句话）

整套收益估计都建立在「步骤分单调、可累积、可停靠保住」这一未核实的计分假设上——若真实赛制是终态计分，则「分数停靠」失效，必须把 FTC 重写为「状态维持型容错」，本轮所有定量结论都要重算。
