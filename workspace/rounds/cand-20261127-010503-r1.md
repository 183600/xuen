## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（多机评测 → 你调的不是一台机器人，而是一支舰队；机器身份是第 6 条泛化轴）**

直觉：大多数队伍会在「自己那台/那几台」上把成功率刷得很高，但评测是在 N 台随机顺序的 G1 上跑。相机外参、曝光/白平衡、桌面高度、关节零位、夹爪磨损、网络路径，每一台都略有不同。于是「平均成功率」实际上是对**机器分布**求期望，而一台标定偏了的机器会成块地丢 episode。反直觉点：多机评测的最大风险不是「平均性能不够」，而是**机器间方差**——一个只对某台标定过拟合的策略，在随机分配下会被最差机器支配。

严谨定义：设机器 r∈{1..N}，策略在机器 r 上的任务成功概率为 p_r(θ)。若舰队/分配固定，则 S 的上限被锁在 `mean_r p_r`，最差机器直接拉低均值；若舰队或分配在多次评测间变化，则 `S` 的方差含一个**组间分量** `Var_r(p_r)/N_eff`，它**不能靠在同一台机器上多跑 episode 消除**。两种情形指向同一结论：必须显式优化「最差机器/组间差异」，而不是只优化平均。

**灵感 2（评测指标 → 主指标是成功率，步骤分只是平局键；优化目标必须换）**

直觉：榜单是字典序 `(平均成功率 S, 平均步骤分 P, 更早提交 T)`。这彻底改变资源分配。S 是 320 个 Bernoulli 的均值，**任何一次额外成功的边际价值恒为 1/320 ≈ 0.31pp，与任务难度无关**。所以不该「把强项刷到 100%」，而该**抬地板**：优先修那些「只差一个可修复瓶颈就能从 0/10 变 1/10」的任务。步骤分只在 S 打平时才值钱——它是二阶目标，不是一阶。反直觉点：**在榜首 <30% 的低分区，最大化平均成功率 ≈ 最大化「至少成功一次的任务数」；把 10 个任务从 0 抬到 1，胜过把 1 个任务从 0 抬到 10。**

严谨定义：`S = (1/320) Σ_{t,i} y_{t,i}`，`P = (1/320) Σ_{t,i} s_{t,i}`，排名键 `(S, P, −T_submit)` 降序。由于 `∂S/∂y_{t,i} = 1/320` 恒定，研发预算应按**「每单位成本带来的边际成功概率」**分配（成本效益背包），而不是按任务难度或当前分数分配；`P` 只在 `S` 相等时进入目标，应作为条件目标而非主损失。

**灵感 3（多机 + 指标 → 评测是一个高噪声统计实验；要优化期望排名，不是期望分数）**

直觉：320 次 Bernoulli，p≈0.3 时 S 的 95% CI 约 ±5pp；榜首区间的队伍差距很可能小于噪声，再叠加机器组间方差，单次榜单名次有很大运气成分。正确做法：(a) 用配对/分层设计比较（同任务、同泛化类型、同机器），用 McNemar / cluster bootstrap，而不是看裸 ΔS；(b) 降低方差本身就有价值（机器不变、动作确定性、每端口状态隔离、延迟抖动小）；(c) 利用第三平局键「更早提交」——先交一个合法基线占位，再迭代（待核实提交规则）。反直觉点：**在高噪声榜单上，「稳定」比「峰值」更接近赢；评测运营（端口、隔离、延迟抖动、统计显著性）不是后勤，是计分的一部分。**

**三者统一**：多机评测把「泛化」从数据分布扩展到**机器分布**；评测指标把「优化目标」从「刷高分」改写为**字典序 (S, P, T) 的期望排名**；二者合起来说明：本轮胜负手从第 2 轮的「数据引擎」进一步外扩到**「机器不变 + 指标感知的评测运营」**——数据仍重要，但决定排名的是「能否在 N 台机器 × 320 次 × 高噪声下稳定抬地板」。

> 本轮主题：**评测协议即优化对象**。主指标是 32 任务平均成功率（S），步骤分（P）只是平局键，提交时间（T）是第三平局键；评测在 N 台随机顺序真机上并行（第 6 条隐性泛化轴）。

## 0. 指标的形式化（本轮所有方案的共同地基）

设任务 `t=1..32`、每任务 `i=1..10` 次独立运行，成功 `y_{t,i}∈{0,1}`、步骤分 `s_{t,i}∈[0,100]`：

```
S = (1/320) Σ_{t,i} y_{t,i}                 # 主键：32 任务总体平均成功率
P = (1/320) Σ_{t,i} s_{t,i}                 # 次键：总体平均步骤分
Rank key = (S, P, −T_submit)  降序          # T 越小（越早提交）越靠前
```

三个直接推论（后续所有决策引用它们）：

1. **边际价值恒定**：`∂S/∂y_{t,i} = 1/320 = 0.3125pp`。任何一次额外成功，无论发生在哪个任务，价值相同 → 预算按「每单位成本的边际成功概率」分配，而不是按任务难度/当前分数分配。
2. **步骤分是条件目标**：`P` 只在 `S` 打平时进入排序。因此 I5 的恢复/进度应定位为「平局键投资」，不能挤占抬地板的主预算。
3. **噪声量级**：独立近似下 `Var(S)=Σp(1−p)/320²`；`p=0.3` 时 `sd≈2.56pp`，95% CI≈±5.0pp。单任务 10 次的 CI≈±28pp。**任何小于配对 CI 的 ΔS 都不构成证据（PR8）。**

机器轴的形式化：设机器 `r`、每台承担约 `320/N` 次。若舰队固定，`S→mean_r p_r`，最差机器直接压低上限；若舰队/分配随机，`Var(S)` 含组间分量 `≈Var_r(p_r)/N`，**不能靠在单机上多跑 episode 消除**。所以 I10 的目标不是「平均更高」，而是「压缩 `Var_r(p_r)` 并抬高 `min_r p_r`」。

## 1. 创新点详述

### I1 v3 六轴增广引擎（新增机器轴）★★★★★
- **动机**：官方 5 类泛化轴（F21/F23）之外，评测协议强制引入机器轴（F20/F23）；只按 5 轴增广的策略仍会在标定不同的机器上成块失败。
- **与 v2 差异**：新增第 6 轴，且增广配比按官方「5 类 × 每类 2 次」的**分层结构**采样，而非任意随机。
- **机器轴的可增广量**（按可实施性排序）：光度（曝光/白平衡/伽马/色温/噪声/运动模糊）→ 几何（高相机小角度旋转/平移/裁剪/缩放；桌面平面单应微扰）→ 本体（关节零位小偏置、夹爪开合标定偏置、动作执行滞后）→ 通信（观测延迟抖动、chunk 执行抖动）。
- **技术可行性**：高。光度与延迟轴在 dataloader 内实时做，零额外存储；几何轴用单应 warp（注意：只 warp 观测会与本体感知不一致，需限制幅度或成对扰动动作坐标系，见风险）。
- **落地**：①按 F13 的跨场次/跨机数据估计各 nuisance 的真实幅度；②每轴 3 档剂量；③L0 剂量-响应（指标同时看平均与**最差组**）；④只保留「不伤标称且压缩组间方差」的轴。
- **风险**：几何增广若只改图像不改动作标签，会注入标签噪声 → 限制为小幅光度/延迟轴先行，几何轴必须在仿真或成对坐标变换下做。

### I2 v3 数据引擎 2.0（机器多样性 + 成功优先门禁）★★★★★
- **动机**：机器轴需要「跨机/跨场次」真实变异作为增广校准源；同时主指标是成功率，数据筛选必须以成功为目标，而非仅拟合动作。
- **与 v2 差异**：①把 DiverseManip（F13，官方自述跨场次差异、物体随机摆放）纳入**机器轴校准集**与低权重共训；②新增**成功优先门禁**：任何数据/增广若提升动作似然而**降低**标称成功率（L0 代理），默认拒绝；③孪生加权 patch 保留（F11 的 weight 不生效问题）。
- **可行性**：高（单卡 LoRA 起步，F11）。
- **风险**：跨场次数据与正赛相机配置不一致 → 先核对 4 相机命名/分辨率/安装角，只取可对齐子集。

### I6 v3 舰队服务：恰好 N 端口 + 状态隔离 + deadline-aware 并发 ★★★★★（↑）
- **动机**：F20 把「部署」变成硬约束——端口数必须**精确等于 N**，N 到评测时才公布；共享 backend 还可能串状态（P9）。F22 又把**延迟波动**纳入可信度评估。
- **六要素**：
  1. **端口契约**：从环境变量 `UNIBOT_N_PORTS` 读取 N；启动预检 `bind(8765..8765+N−1)`，任一失败或检测到多余端口 → fail-fast；调试端口放独立区间，绝不混入 8765 段。
  2. **拓扑选择器**：测量单模型显存 `M` 与单步时延 `L`；若 `N·M ≤ 0.8·GPU_mem` 且 `N·L ≤ 0.5·周期`，用拓扑①（N 独立进程，最稳）；否则拓扑②（共享 backend + N 端点 + 中央批处理队列）。
  3. **状态隔离契约**：`EpisodeState` 按连接/端口键控；`reset(session)` 只清该键；禁止模块级可变全局、禁止跨端口共享 RNG/运行统计；每端口预分配输入输出 buffer。
  4. **并发与延迟**：请求带 deadline；只有当批内所有请求都能在各自 deadline 前完成时才合批，否则紧急请求单独跑；固定 `action_chunk_size` 与 `image_resize` 形状，`torch.inference_mode()` + CUDA Graph，启动后与 `reset` 后各做一次全路径 warmup，避免首步离群。
  5. **故障隔离**：单端口 worker 崩溃只重启该端口；评测端重连时接受并只 reset 该端口；健康探针 + 结构化日志（端口、p50/p99、抖动、异常动作率）。
  6. **凭据**：所有端口同一 token；`meta.token` 每步回传（README §4）。
- **可行性**：高（官方 `PolicyService`/msgpack 可直接改造，F12）。
- **落地**：①N 端口预检脚本；②双端口串扰 fuzz（交错发送不同指令/历史，断言各端口输出只依赖自身流）；③N 并发压测（p99/抖动/显存）；④warmup 与断线重连回归。
- **风险**：拓扑②的并发批处理会拉高 p99 尾部；若 F22 的可信度指标进入排名，宁可牺牲吞吐选拓扑①或分片，也不要抖动。

### I8 v3 评测运营闭环：统计协议 + 指标注册表 + 早提交 ★★★★★
- **动机**：高噪声榜单 + 稀缺真机预算；必须避免「把噪声当增益」和「把步骤分当主目标」。
- **本轮新增**：
  1. **统计协议**：配对/分层比较（任务 × 泛化类型 × 机器）；二值成功用 **McNemar**，连续步骤分用 **cluster bootstrap（按任务/机器聚类）**；报告 95% CI；L2 准入要求 `ΔS` 的下置信界 > 0（或 S 打平时 `ΔP` 显著）。
  2. **指标注册表**：每次运行记录 `S, P, per-task success, per-task step, latency p50/p99/jitter, action anomaly rate, port uptime, N`；滚动校准「离线代理 → 真机 ΔS」的 Spearman（承接第 2 轮注册表）。
  3. **早提交策略**：第三平局键是更早提交（F21）。先交一个**合法且可运行**的基线占位；后续每次改进都保留可回滚版本（待核实提交次数/以最新还是最优为准）。
  4. **预算分配**：见 I11。
- **可行性**：高（纯脚本 + 表格）。
- **风险**：单任务通道分布偏移（F25）→ 只用它做**相对排序**，绝对 ΔS 必须由全量运行锚定。

### I10 机器不变策略（Machine-Invariant Policy, MIP）（新）★★★★★
- **动机**：机器轴（F23）是唯一未写在考纲、却由协议强制的泛化轴；组间方差不能被「多跑几次」平均掉。
- **与现有方案差异**：普通队伍靠「多机数据平均化」隐式适应；本点显式做三件事：**训练期机器增广**（造机器分布）、**reset 期标定归一化**（消观测 nuisance）、**组鲁棒目标**（压最差机器）。
- **技术方案**：
  1. **机器指纹 φ（reset 期一次估计）**：从首 K 帧 + 本体读数估计低维向量：图像亮度/白平衡/背景直方图、桌面平面单应（检测桌面边缘/平面拟合）、夹爪闭合时的零位读数、关节读数与图像的一致性。φ 只用于**确定性归一化**或作为**输入条件**，不做在线学习。
  2. **归一化优先于条件化**：能消掉的 nuisance（光度、桌面平面、分辨率）直接做直方图匹配 + 单应 warp 到规范桌面系；剩余难消的（夹爪磨损、关节零位）用 φ 作为 FiLM/token 条件注入。
  3. **训练期机器增广**：用 I1 v3 的机器轴合成 φ 与观测，使策略在训练中见过「φ→如何补偿」的配对。
  4. **组鲁棒目标**：按机器/场次分组，优化 `L = (1−λ)·E[L] + λ·CVaR_α(L_group)`；λ 从小开始，L0 验证不伤标称。
- **与单模型边界（PR2）**：归一化是确定性预处理；φ 条件化只是同一模型的额外输入；组鲁棒只是训练目标。**但仍需组委会书面确认**「reset 期确定性标定 + 机器条件输入」不属于在线适应/多模型。
- **所需资源**：增广与归一化 1×24GB；φ 估计 CPU 即可（<100ms）；组鲁棒训练与主训练同卡。
- **落地**：①nuisance 清单与可观测性排序；②归一化原型（光度 + 桌面单应）；③机器增广与 φ 条件化；④L0 组消融（标称、单轴、组合）；⑤单任务通道 A/B；⑥真机抽测最差机器。
- **风险**：过度归一化抹掉任务相关线索（如颜色任务的颜色）→ 归一化必须**任务条件化**（ColorArrangement 等颜色敏感任务禁用颜色归一化）；几何 warp 误估桌面平面 → 置信门控，超阈退回原始输入。

### I11 指标感知组合分配（Metric-Aware Portfolio Allocation, MAPA）（新）★★★★★
- **动机**：S 的边际价值恒定（§0），所以「把预算给最弱任务」是错的；应给「每单位成本最可能多换来一次成功」的任务。低分区（榜首 <30%）下，抬地板 ROI 远高于刷强项。
- **与现有方案差异**：常见做法按当前分数/难度排序任务；本点按**边际成功概率 / 成本**排序，并用分层统计控制噪声。
- **技术方案**：
  1. **候选干预** `j=(task, fix)`；估计 `Δp_j`（L0 代理 + 单任务通道相对信号 + 少量全量锚点校准偏差）；`ΔS_j = Δp_j/32`。
  2. **成本效益背包**：在预算（GPU-日 + 真机时段）约束下最大化 `Σ ΔS_j`，带不确定性惩罚（UCB 或 P(improve)）。
  3. **可恢复性优先**：从 L0 扰动判断失败是「差一个可修复瓶颈」还是「技能缺失」；前者优先（低成本抬地板），后者后置。
  4. **序贯停止**：每轮全量运行后用配对 CI + alpha-spending，避免「盯着榜单反复调」的 peeking 偏差。
  5. **平局键**：当多个候选 `S` 统计上不可区分时，选 `P` 更高者；再平则选能更早提交的。
- **可行性**：高（离线 + 表格 + 少量真机）。
- **风险**：`Δp_j` 估计偏差（单任务通道分布偏移）→ 用全量锚点做偏差校准；只信相对排序，不信绝对值。

### 其余创新点（维持/降级）
- **I3** 接触任务族关键点伺服：维持；机器轴标定对接触段几何更敏感，优先纳入 I10 归一化。I3' 降级预案不变。
- **I4** 人手干预门控 + 自适应 chunk：维持；延迟抖动轴与 I6 v3 共用测量。
- **I5** 非标称示教 + 得分点恢复：**降为二阶目标**（P 只在 S 平局时计分）；仍做 3 任务试点，但不吃主预算。
- **I7** 世界模型前瞻：维持 ★★（缓）；按 N 并发后的 p99 重算延迟余量，不足即裁撤。
- **I9** reset 期检索：维持；检索前先做 I10 的机器归一化，避免把机器外观差异误当物体差异。

```python
import numpy as np

def leaderboard_key(S, P, T_submit):
    return (S, P, -T_submit)          # 降序：S 主键，P 次键，越早提交越前

def marginal_success_value():
    return 1.0 / 320.0                # 0.3125pp / 每次成功

def paired_mcnemar(y_a, y_b):
    # y_a, y_b: 同一 (task, gen_type, machine) 单元上的配对 0/1
    b = np.sum((y_a == 1) & (y_b == 0))
    c = np.sum((y_a == 0) & (y_b == 1))
    # H0: b ~ Binomial(b+c, 0.5)；返回精确二项 p 值与 ΔS
    from math import comb
    n = b + c
    p = min(1.0, 2 * sum(comb(n, k) for k in range(0, min(b, c) + 1)) / 2**n) if n else 1.0
    return {"delta_S": (b - c) / 320.0, "p_value": p, "discordant": n}

def cluster_bootstrap_deltaS(y_a, y_b, task_ids, B=2000, seed=0):
    rng = np.random.default_rng(seed)
    tasks = np.unique(task_ids)
    diffs = []
    for _ in range(B):
        pick = rng.choice(tasks, size=len(tasks), replace=True)
        idx = np.concatenate([np.where(task_ids == t)[0] for t in pick])
        diffs.append((y_a[idx].mean() - y_b[idx].mean()))
    lo, hi = np.percentile(diffs, [2.5, 97.5])
    return lo, hi                     # 只有 lo > 0 才允许进 L2（PR8）
```

### 2.2 成本效益分配（I11）

```python
def allocate(interventions, budget, lam_unc=0.5):
    # interventions: [{task, d_p, cost, unc}]，d_p = 估计的边际成功概率提升
    # 目标：max Σ (d_p/32) x_j − lam_unc·Σ unc_j x_j，s.t. Σ cost_j x_j ≤ budget
    # 这是 0/1 背包；32 任务 × 少量候选，DP 即可精确解
    items = [(max(0.0, it["d_p"]) / 32.0 - lam_unc * it["unc"], it["cost"], it)
             for it in interventions]
    # ... 标准 DP，返回选中的 intervention 集合
    return knapsack(items, budget)

# 反直觉示例：A: p 0→0.1, cost 1；B: p 0.8→0.9, cost 10
# 两者 ΔS 都是 0.1/32，但 A 的 ROI 是 B 的 10 倍 → 低分区先抬地板。
```

```python
class MachineInvariantPolicy:
    def reset(self, first_obs=None):
        self.state = EpisodeState()
        if first_obs is None:
            return
        phi = estimate_machine_fingerprint(first_obs)      # 光度/桌面单应/零位
        self.canon = make_canonicalizer(phi)               # 确定性，无在线学习
        self.machine_token = phi_to_token(phi)             # 供 FiLM/token 条件化
        # 颜色敏感任务禁用颜色归一化（任务条件化）
        if is_color_task(first_obs["observation.language"]):
            self.canon.disable_color_norm()

    def get_action(self, obs):
        if not self.state.inited:
            self.reset(obs); self.state.inited = True
        obs_n = self.canon(obs)                            # 归一化观测
        chunk = self.vla.propose_chunk(obs_n, cond=self.machine_token)
        return self.guard_stack(chunk, obs_n)

def group_robust_loss(losses_by_machine, lam=0.1, alpha=0.8):
    # CVaR_alpha over worst machines
    losses = sorted(losses_by_machine.values(), reverse=True)
    k = max(1, int(round((1 - alpha) * len(losses))))
    cvar = sum(losses[:k]) / k
    return (1 - lam) * (sum(losses) / len(losses)) + lam * cvar
```

### 2.4 舰队服务（I6 v3）

```python
def preflight_ports(N, base=8765):
    for p in range(base, base + N):
        if not can_bind(p):
            raise SystemExit(f"port {p} unavailable; need exactly {N} ports")
    if can_bind(base + N):
        raise SystemExit("extra port in reserved range; evaluator requires exact N")
    return [base + i for i in range(N)]

class FleetServer:
    def __init__(self, policy_factory, N):
        self.ports = preflight_ports(N)
        self.states = {p: EpisodeState() for p in self.ports}   # 每端口隔离
        self.backend = SharedBackend(policy_factory) if USE_SHARED else None

    def on_reset(self, port):
        self.states[port].clear()                              # 只清本端口

    def on_action(self, port, obs):
        req = Request(port=port, obs=obs, deadline=now() + PERIOD - SAFETY)
        if self.backend:
            return self.backend.submit(req, batch_if_all_before_deadline=True)
        return self.workers[port].infer(req)
```

**双端口串扰 fuzz（必测）**：开两端口，交错发送不同 `observation.language` 与不同历史；把各端口输出与「单独运行同一流」的输出逐元素比对；再在端口 A 调 `reset`，断言端口 B 的输出不变。

## 3. 实验设计（v1.2：加入机器轴与统计协议）

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0 | I1 机器轴剂量-响应（光度/几何/零位/延迟）；I10 归一化与组鲁棒；I2 成功优先门禁；I5 合成示教 | 离线（免费） | 标称 ΔS≥0 **且**最差组 ΔS>0；组间方差下降；否则拒绝该轴 |
| L0-stat | 代理指标→真机 ΔS 的相关性（注册表） | 离线 | Spearman>0.6 的代理才可单独准入 L2 |
| L1 | 2^(k−p) 析因：{机器增广, 归一化, φ 条件化, 组鲁棒} × {on/off}；guard 栈 3 模块 | 离线 + 少量单任务通道 | 主效应显著的 ≤3 个组合进 L2；单任务结果只作相对排序 |

| Fleet | N 端口预检 + 双端口串扰 fuzz + N 并发 p99/抖动 + 断线重连 | 本地 stub + 压测 | 端口数精确、零串扰、p99<40ms、抖动有界、单端口故障不扩散 |

**比较协议**：A/B 必须共享任务、泛化类型与机器；成功用 McNemar，步骤分用按任务聚类的 bootstrap；报告 CI 与效应量；禁止用单次榜单的裸名次下结论。

## 4. 预实验/解析推导（示意性，非真机结果）

- **边际价值**：多成功 1 次 = `1/320 = 0.3125pp`。若把 10 个任务各从 0/10 抬到 1/10，ΔS = `10/320 = 3.125pp`；若把 1 个任务从 0/10 刷到 10/10，ΔS 相同但成本通常高一个量级 → 抬地板 ROI 更高。
- **噪声**：`p=0.3, n=320` → `sd=√(0.21/320)=2.56pp`，95% CI≈±5.0pp；单任务 `n=10` → CI≈±28pp。结论：单任务单次差异不可用；必须配对/聚合。
- **机器组间方差**：设 N=4，`p_r={0.2,0.3,0.3,0.4}`，`mean=0.3, sd_r=0.0816`。若舰队/分配随机，组间对 `Var(S)` 的贡献 `≈sd_r²/N=1.66e−3`（sd≈4.1pp），大于同规模 within 分量（`0.21/320≈6.6e−4`，sd≈2.6pp）。示意性说明：**机器异质性可以主导榜单噪声**，这正是 I10 的立项理由（真实数值需用 Runs 数据估计）。
- **端口契约**：若真实 N=4 而只暴露 3 个端口，按 README §5 直接不满足交互要求——这不是性能损失，是**整场评测失败**。故 I6 v3 的预检优先级高于任何模型改进。
