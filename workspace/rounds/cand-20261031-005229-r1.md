# 第 13 轮（新循环第 1 轮）· PART-LOOP：最后 3 厘米不只是「什么时候闭环」，还是「闭环到哪个部位」

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新一轮灵感循环的第 1 轮，三个词是「创新点」「评测基准」「语义分割」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是补上它们共同缺的一个空间语义层：**功能部位（functional part）**。

## 0. 先说我本轮改了什么判断

上一轮 CHUNK-SERVO 的判断是：最后 3 厘米失败，是因为我们设的 30 步开环 chunk 执行时，接触发生在 chunk 内部，模型来不及看。这个判断我仍然保留。

但本轮检索和读数据之后，我认为它还漏了一半：

> **最后 3 厘米不只是「什么时候看」，还是「看哪个点」。**

VLA 对齐的是「物体」，不是「功能部位」。杯子有把手，网线有 RJ45 卡扣，锁有钥匙孔，试管有管口，拉链有拉头，充电器有插脚，瓶盖有螺纹。物体级 6D 位姿不够，因为**接触点不在物体质心**。一个把「杯子」放到杯架附近的策略，可能抓的是杯口而不是把手；一个把「网线」插进端口的策略，可能捏的是线身而不是卡扣。这些失败在物体级成功率里都记 0，但在 part 级诊断里是两种完全不同的错误，需要两种完全不同的干预。

所以本轮把问题从「物体级操作」推进到「功能部位级操作」。CHUNK-SERVO 负责「什么时候看」，PART-LOOP 负责「看哪个点」。

## 1. 本轮先核实事实：四个会改变方案的发现

### 1.1 官网榜单当前不可复核，29.7% 只能当历史记录

2026-10-31 我重新抓取 `unibot.unitree.com`，所有页面（首页、challenges、leaderboard、runs、`leaderboard_data.json`）都返回 **HTTP 567**，页面是腾讯云 EdgeOne 的「请求已被站点的安全策略拦截」。搜索引擎快照显示首页/榜单/运行记录都是「**即将发布 / Coming Soon**」。

这意味着：

- 上一轮记录的 MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9% 等数字，本轮**无法从官网复核**；
- 上一轮已经用公开 JSON 证明榜单的 step~success 回归 R² > 0.999999、每任务成功率不是 10% 的整数倍、32 个任务视频是占位符；
- 因此本轮**不把任何榜单数字当 SOTA、当难度表、当失败分布**。29.7% 只作为「历史记录/难度信号」引用。

这反而强化了本轮的方向：**如果官方榜单本身不可复核，参赛队更需要一个自己的、可重复的评测基准。** 这就是「评测基准」这个词落到方案里的第一层。

### 1.2 32 任务名单要修正：上一轮有 3 处命名错位

我通过 HuggingFace API 读取 `unitreerobotics/unibot-v1-challenge-dataset` collection，确认它正好包含 **32 个数据集**。上一轮任务表里有 3 处与官方数据集不一致：

| 上一轮写法 | 官方数据集名 | 说明 |
|---|---|---|
| T25 StackCups | **StoreCups** | 官方没有 StackCups；纸杯堆叠是 PaperCupStacking，收纳纸杯是 StoreCups |
| T23 StoreRacket | **StorePaddle** | 官方是乒乓球拍 StorePaddle |
| T02 Fruit Basket Collection | **FruitCollection** | 官方数据集名是 FruitCollection |

这不是文字问题：任务名错位会导致数据映射、语言指令、目标库和单任务通道选错。本轮产物区以 HF collection 的 32 个名字为准，重新排表。

### 1.3 腕部相机**有内参**；头双目标定逐数据集不同

上一轮写「腕部相机没有内参矩阵」。本轮逐个读取 32 个数据集的 `meta/info.json`，发现这是错的：

- `camera_params.wrist_left.color.camera_matrix` 和 `wrist_right` 都有完整内参；
- 32 个数据集的腕部 fx 在 **432.89–437.49 px**，cx≈324，cy≈243，畸变模型是 `distortion.inverse_brown_conrady`；
- 头双目也有完整内参、畸变、R/T、`rectified: true`，但 **fx 在 186.03–296.15 px、基线在 46.42–63.24 mm 之间逐数据集变化**，不是一个全局的 282.37 px / 58.25 mm。

这有两个直接后果：

1. **腕部 2D 视觉伺服/部位分割的可行性大幅提高**，不再需要先做一次棋盘格标定才能用；
2. **头双目深度必须用每个数据集/每台机器人自己的参数**，不能把 HangCup 的 58.2526 mm 当成所有任务的标准。上一轮「头双目已标定、基线 58.2526 mm」的说法只对 HangCup 等部分数据集成立。

腕部仍然缺的是 **wrist→EE 的外参**（`camera_params` 里没有手眼矩阵），所以腕部 3D 需要一次手眼标定或用头部双目兜底；但腕部 2D 部位掩码、2D IBVS、近景验证已经可用。

### 1.4 数据里已经藏着 part 标签的「答案」

我读取了 32 个数据集的 `meta/tasks.parquet`，每个任务有 **5 条同义语言指令**（例如 HangCup 的 5 条都围绕「cup / cup rack / marked spot / hook」）。这很重要：

- 官方 API 每局只给一条 `observation.language`，但数据里有 5 条同义改写，可以做语言鲁棒性训练；
- 指令里大量出现功能部位词：`marked spot on the cup rack`、`network port`、`test tube rack`、`pencil case zipper`、`bottle cap`、`first socket`、`key`、`syringe`、`push pins`；
- 说明 32 个任务里 **21 个是明确的 part-critical**（见产物区任务表），不是少数特例。

再加上：

- 4 路视频 `head_stereo_left/right`、`wrist_left/right`，480×640，30 fps，AV1；
- `state_d435` 是头相机在 base 系的 6D 位姿，`left/right_ee_pose_gripper_base` 是夹爪在 base 系的 6D 位姿；
- `left/right_gripper` 的 HangCup 统计范围是 0.08–4.78（README 标称 5.5–0.0，open→close）；
- `action.pivot` 的维度名是 `vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height`，HangCup 里 `pivot_3/4/5` 恒为 0/0.15/0。

这意味着：**成功演示在接触帧已经回答了「该抓哪个部位、该对准哪个部位」**。我们不需要从零训练一个分割大模型，只需要把 33k 条成功演示里的这个答案挖出来。

## 2. 为什么「语义分割」是这次的关键词，而不是再训一个分割模型

如果我上来就说「加一个 SAM 3 在线分割」，会同时踩两个坑：

1. **规则坑**：比赛要求所有任务基于同一模型，不得混合多个模型测试；在线跑 SAM 3 + VLA 会被质疑是第二个模型；
2. **工程坑**：SAM 3 在线推理会增加延迟，而官方评测会记录每步延迟和动作规律，延迟不稳会直接影响结果可信度。

所以本轮的分割不是「在线感知模块」，而是**离线标签工厂**：

> 用 SAM 3 的一键种子 + 视频跟踪，把 33k 条成功演示变成 part 级掩码和接触标签；这些标签同时服务评测、训练、控制三件事。推理时只有官方 WLA 一个 checkpoint，SAM 3 不出现。

具体怎么做：

- **一键种子**：每个任务选 1 个 canonical episode，人在 1–3 个关键帧上点 1–3 个功能部位（grasp part、target part、articulation part）。32 个任务 × 2–3 个部位 ≈ **64–96 次点击**。
- **视频跟踪**：用 SAM 3 的 concept / exemplar prompt 在该 episode 内传播；再用这个掩码作为 exemplar，跨 episode 初始化。
- **多视图融合**：头部双目给 3D 质心和表面点；腕部近景给 2D 掩码和接触细节；`state_d435` + 相机内参把夹爪投影到头图，`gripper` 闭合时刻给接触帧。
- **置信度门控**：掩码跨帧稳定性、双目一致性、夹爪-部位距离三项打分；低置信度的任务（透明试管、反光杯、细拉链头）回退物体级，不硬做 part 级指标。

这套东西的产物不是「一个更强的分割模型」，而是 **32 个任务的 part ontology + 33k episodes 的 part 标签 + 一套可复现的 part 级评测**。这是「评测基准」和「语义分割」两个词的合流点。

## 3. 新想法：PART-LOOP

PART-LOOP 是一个三层闭环，不是又一个模型名：

```text
        ┌─────────────────────────────────────────────┐
        │  1. PART-BENCH（评测层）                     │
        │  32 任务 × 5 泛化轴 × 8 个 part 指标         │
        │  用 33k 成功演示 + 反事实变换离线跑           │
        └───────────────┬─────────────────────────────┘
                        │ 失败诊断：哪个任务/轴/部位
                        ▼
        ┌─────────────────────────────────────────────┐
        │  2. AFFORD-HEAD（模型层）                    │
        │  官方 WLA + 功能部位辅助头/隐式对齐           │
        │  推理仍是一个 checkpoint                     │
        └───────────────┬─────────────────────────────┘
                        │ part 热图/特征
                        ▼
        ┌─────────────────────────────────────────────┐
        │  3. PART-SERVO（控制层）                     │
        │  CHUNK-SERVO 的目标从物体质心换成功能部位     │
        │  5 步执行块内 part 级 IBVS/PBVS              │
        └───────────────┬─────────────────────────────┘
                        │ 新的失败样本
                        └──────────► 回到 1（数据飞轮）
```

### 3.1 PART-BENCH：part-level 反事实评测

官方评测是 32 任务 × 10 次，5 类泛化各 2 次。它的问题是：

- 只有二值成功/步骤分，不能告诉你失败在「没抓对部位」「抓对了但差 2 mm」「抓稳了但放错目标部位」「被人移动后不恢复」中的哪一种；
- 320 trials 很贵，不能每个想法都上真机；
- 官方榜单当前不可复核，不能当日常迭代的反馈信号。

PART-BENCH 的做法是：**对同一条成功演示做反事实变换，测策略的动作/接触点是否等变、不变、可恢复。** 五个轴对应官方五类泛化：

| 泛化轴 | 反事实变换 | 期望性质 | 指标 |
|---|---|---|---|
| 位置 | 把目标物体/受器平移 ΔT | 动作应等变：`a(T·obs) ≈ T·a(obs)` | EQ_pos、PGA |
| 干扰物 | 在桌面合成无关物体掩码 | 接触点不应转向干扰物 | DI、PGA |
| 背景 | 替换桌面背景纹理 | 动作应不变 | BI、PAE |
| 未见物品 | 换同类不同外观的物体 | 仍应抓/对准功能部位 | UOT、PGA |
| 人为干扰 | 在 t 与 t+1 之间移动目标部位 | 应在 N 帧内重新对准 | HIR、恢复时间 |

八个 part 指标：

1. **PGA（Part Grounding Accuracy）**：预测接触时刻，夹爪投影是否落在正确的 grasp-part 掩码内；
2. **PAE（Part Alignment Error）**：接触前夹爪 TCP 到 target-part 表面的 3D 距离；
3. **PTC（Part Transport Consistency）**：接触后部位位移与夹爪位移的相关性，判断是否抓稳；
4. **GPE（Goal Part Error）**：终局时物体 grasp-part 与 target-part 的相对位姿误差；
5. **DI（Distractor Invariance）**：干扰物合成前后接触点/动作的变化；
6. **BI（Background Invariance）**：背景替换前后动作的变化；
7. **UOT（Unseen Object Transfer）**：换物体后是否仍命中新物体的功能部位；
8. **HIR（Human Interference Recovery）**：目标被移动后多少帧内重新对准。

这些指标都能在离线演示/反事实图像上算，不需要真机闭环。它们不是官方成功率的替代品，而是**诊断信号**。校准方法：在单任务不计分通道选 5 个任务，跑 20 次真机，拟合 PART-SCORE 与真实成功率的秩相关；**ρ ≥ 0.7 才用它选任务，ρ < 0.5 就只用于失败分诊**。

### 3.2 AFFORD-HEAD：把 part 标签变成在线单模型先验

这是本轮真正押注模型的地方。官方 WLA 是 6B，VLM 冻结、只训 DiT action head + robot-state projector，单张 24GB 可跑。我们在它的视觉塔上做两种实现，按门控二选一：

- **A1 隐式对齐（AffordVLA 路线）**：训练时用 SAM 3 的 part 特征做 teacher，对齐 WLA 中间视觉 token 的 affordance 表示；推理时 teacher 丢弃，零额外延迟。适合延迟敏感、想要「一个 checkpoint」的情况。
- **A2 显式热图（MAST-VLA 路线）**：加一个轻量 part heatmap head，把热图作为 action head 的空间先验；可解释、可可视化，推理多一个轻量头（目标 <10ms）。

训练目标：

```text
L = L_action + λ1 · L_part + λ2 · L_align + λ3 · L_smooth
```

- `L_action`：官方 WLA 的 flow-matching / diffusion action loss；
- `L_part`：part 掩码 BCE/Dice（A2）或 part 特征余弦对齐（A1）；
- `L_align`：VLA 视觉 token 与 SAM 3 teacher 特征的隐式对齐（A1）；
- `L_smooth`：part 热图/特征的时序平滑，避免夹爪附近闪烁。

为什么 part 级表示可能比 object 级更抗泛化轴：

- **未见物品**：part 是类别级功能区域（把手、瓶盖、卡扣），不是实例外观；
- **干扰物**：part 掩码只看目标区域，不被杂物分散；
- **背景**：part 表示局部，不依赖全局纹理；
- **位置/人为干扰**：part 位姿变了，相对目标跟着变，不需要重新学「物体长什么样」。

这与上一轮 CHUNK-SERVO 的「相对目标」是同一哲学：**把绝对外观/绝对位置换成相对功能关系**。区别是上一轮相对的是「受器→夹爪」，这一轮相对的是「功能部位→夹爪」。

### 3.3 PART-SERVO：把 CHUNK-SERVO 的目标从物体质心换成功能部位

CHUNK-SERVO 原来的目标是 `T_base_target`（受器/物体在 base 系的位姿）和 `T_target_ee*`（演示检索的相对位姿）。本轮把 `target` 从物体级换成 part 级：

```text
离线：T_part_ee*(k) = T_base_part(k)^-1 · T_base_ee(k)
在线：T_base_ee^d(t) = T_base_part(t) · T_part_ee*
误差：e(t) = log( T_base_ee(t)^-1 · T_base_ee^d(t) )
```

- 远距离用头部双目 + part 3D 质心做 PBVS；
- 近距离用腕部 part 掩码做 2D IBVS（腕部内参已核实，fx≈433–437）；
- 接触段法向缩幅、切向保留；
- part 掩码置信度低 → 回退物体级 → 再回退 VLA 开环；
- 人为干扰 → 重新分割/跟踪 part → 更新 `T_base_part` → 恢复伺服。

这把「最后 3 厘米」拆成两个可测的子问题：**抓对部位（PGA）** 和 **对准部位（PAE）**。前者靠 AFFORD-HEAD，后者靠 PART-SERVO。

## 4. 与第 10/11/12 轮的关系：四层拼图，不是四套方案

| 轮次 | 层 | 回答的问题 | 本轮怎么用 |
|---|---|---|---|
| 第 10 轮 FACT-VLA | 相位层 | 现在处于哪个阶段？ | part 标签只在接触/对准相位启用 |
| 第 11 轮 GEO-RESIDUAL | 信号层 | 场景变化能否被我的动作解释？ | 触发 part 重定位/人为干扰恢复 |
| 第 12 轮 CHUNK-SERVO | 时间层 | 多久看一次？ | 30 步规划 + 5 步执行 |
| **第 13 轮 PART-LOOP** | **空间语义层** | **看哪个部位？** | **part 目标 + part 评测 + part 先验** |

四层拼起来是：

```text
phase（现在做什么）
  → part（接触哪个功能部位）
    → servo（5 步内怎么修正）
      → chunk（什么时候重新看）
```

这不是推倒重来，而是把前三轮缺的「接触点语义」补上。上一轮说「最后 3 厘米是控制频率问题」；本轮说「最后 3 厘米还是接触点表示问题」。两者正交，可以叠加。

## 5. 本轮主动剪掉的（防止清单膨胀）

- **不在线跑 SAM 3 / 第二个分割模型**：违反单模型风险 + 延迟；分割只做离线标签。
- **不做端到端 6D 物体位姿网络**：透明、反光、变形物体不可靠；part 级相对目标更稳。
- **不从零训 VLA / 世界模型**：官方 WLA 6B 已开源，算力不划算；DreamZero 14B 路线延迟更差。
- **不做 32 个任务各训一个策略**：规则禁止，且不泛化。
- **不把官方预览榜单当难度表**：当前不可复核，上一轮已证伪其 step~success 线性关系。
- **不追求分割 SOTA**：SAM 3 只是标签工具；我们不为分割精度发论文，只为 part 标签可用。
- **不把 PART-BENCH 当官方成功率的替代**：它只是诊断/选任务；真机单任务通道才是校准锚点。

### 5.1 三个灵感词各落到哪里

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **创新点** | PART-LOOP 三层：PART-BENCH（评测）、AFFORD-HEAD（模型）、PART-SERVO（控制）；核心是把 object-level 换成 part-level | 不发明新的大模型架构；不做在线第二个模型 |
| **评测基准** | PART-BENCH：32 任务 × 5 轴反事实 × 8 指标，并与官方单任务通道校准 | 不把预览榜单当难度表；不做纯分割精度榜 |
| **语义分割** | SAM 3 离线一键种子 + 视频跟踪，把 33k 成功演示变成 part 标签；AFFORD-HEAD 在线单模型使用这些标签 | 不在线跑 SAM 3；不追分割 SOTA；不做第二个分割模型 |

### 1.6 公开模型家族的瓶颈（证据 C，来自上一轮记录 + 本轮判断）

上一轮已经梳理过 MolmoAct2、π0.5、WALL-OSS、GR00T N1.7、DreamZero、X-VLA 等家族。本轮不重复全表，只保留与本轮相关的三条：

1. **object-centric**：多数 VLA 的视觉-语言对齐是物体级/场景级，没有显式功能部位表示；接触点容易落在物体质心附近。
2. **chunk open-loop**：本方案设的 30 步 chunk 内无新观测，接触/对准误差无法修正；CHUNK-SERVO 解决时间维度。
3. **泛化轴数据不足**：5 类泛化里，背景/干扰物/人为干扰在训练数据中覆盖有限；part 级表示和数据增强可以补。

**注意**：由于榜单不可复核，本轮不对具体模型排名，也不声称「某模型一定失败在某个轴」；这些是设计假设，PART-BENCH 会逐任务测。

## 2. 问题形式化

### 2.1 物体级 vs 部位级

官方任务通常可以写成：

```text
给定语言 l、观测 o_t，输出动作 chunk a_{t:t+H-1}，使物体 O 从初始状态到目标状态。
```

物体级表示只关心 `O` 的 6D 位姿 `T_base_O`。但接触/对准发生在 `O` 的某个功能部位 `P` 上：

```text
T_base_O  →  T_base_P = T_base_O · T_O_P
```

`T_O_P` 是部位在物体坐标系里的相对位姿。对杯子，`P` 是把手；对网线，`P` 是 RJ45 卡扣；对锁，`P` 是钥匙孔；对试管，`P` 是管口。`T_O_P` 随物体实例/类别变化，但在同一功能类别内相对稳定。

**核心假设（C）**：part 级目标 `T_base_P` 比 object 级目标 `T_base_O` 更接近接触控制所需的信息，因此对未见物品、干扰物、背景、位置变化更鲁棒。

### 2.2 形式化定义

- **grasp part** `P_g`：夹爪应接触/夹持的功能部位；
- **target part** `P_t`：物体应被对准/插入/放置的受器功能部位；
- **articulation part** `P_a`：需要操作的铰链/拉链/瓶盖等活动部位（可选）；
- **part mask** `M_t^P ∈ {0,1}^{H×W}`：图像上的部位掩码；
- **part pose** `T_base_P(t)`：部位在 base 系的 6D 位姿（由双目/腕部/几何先验估计）；
- **part goal** `T_P_ee*`：演示中部位到夹爪的相对目标位姿。

### 2.3 八个指标

| 指标 | 定义 | 方向 | 对应失败 |
|---|---|---|---|
| **PGA** | 接触时刻夹爪投影落在 `P_g` 掩码内的比例 / 3D 距离阈值内比例 | ↑ | 抓错部位 |
| **PAE** | 接触前 TCP 到 `P_t` 表面的 3D 距离（mm） | ↓ | 最后 3 cm 对不准 |
| **PTC** | 接触后部位位移与夹爪位移的相关系数 / 滑移率 | ↑ | 抓稳但滑脱 |
| **GPE** | 终局 `P_g` 与 `P_t` 的相对位姿误差（mm/deg） | ↓ | 放错目标部位 |
| **DI** | 干扰物合成前后接触点/动作的偏移 | ↓ | 被杂物吸引 |
| **BI** | 背景替换前后动作的偏移 | ↓ | 背景过拟合 |
| **UOT** | 换同类不同外观物体后，PGA/PAE 的保持率 | ↑ | 外观过拟合 |
| **HIR** | 目标部位被移动后，重新对准所需帧数/成功率 | ↑ | 人为干扰不恢复 |

**PART-SCORE**（用于排序，不用于替代官方成功率）：

```text
S_part = w1·PGA + w2·(1-PAE/τ) + w3·PTC + w4·(1-GPE/τ')
       + w5·DI_inv + w6·BI_inv + w7·UOT + w8·HIR
```

权重 `w` 用 5 任务单任务通道的真实成功率做**秩相关校准**，不手工拍。若校准失败（ρ<0.5），`S_part` 只用于失败分诊，不用于选任务。

### 2.4 为什么这八个指标与官方五轴对齐

| 官方泛化轴 | 典型失败 | PART-LOOP 组件 | 指标 |
|---|---|---|---|
| 位置 | 物体移动后仍抓旧位置 | part pose + 相对目标 | EQ_pos、PGA |
| 干扰物 | 抓错物体/被杂物吸引 | part mask + 部位先验 | DI、PGA |
| 背景 | 背景变化导致视觉漂移 | part-centric 表示 | BI、PAE |
| 未见物品 | 外观变化导致抓错部位 | AFFORD-HEAD | UOT、PGA |
| 人为干扰 | 目标被移动后不恢复 | part 重定位 + 编辑检测 | HIR、恢复时间 |

这是本方案与「泛泛做一个 affordance 模型」的最大区别：**每个组件都对应一个官方泛化轴和一个可测指标**。

## 3. 方法

### 3.1 PART-BENCH：从 33k 成功演示挖 part 标签

#### 3.1.1 Part ontology（32 任务）

每个任务一个 JSON 条目：

```json
{
  "task": "HangCup",
  "language_variants": ["Hang the cup on the marked spot on the cup rack.", "..."],
  "grasp_part": {
    "name": "cup_handle",
    "prompts": ["cup handle", "handle of the cup"],
    "seed_frame": 42,
    "seed_point": [312, 240]
  },
  "target_part": {
    "name": "rack_hook",
    "prompts": ["hook of the cup rack", "marked spot on the cup rack"],
    "seed_frame": 80,
    "seed_point": [401, 188]
  },
  "articulation_part": null,
  "success_criteria": {
    "type": "hang",
    "relative_pose": "cup_handle_on_hook",
    "tolerance_mm": 15
  }
}
```

32 个任务先由人工写 ontology（W0），再用 SAM 3 跟踪验证；ontology 不是一次性写死，PART-BENCH 会按失败反馈更新。

#### 3.1.2 一键种子 + SAM 3 视频跟踪

流程：

1. **选 canonical episode**：每任务选 1 条成功、无遮挡、部位清晰的 episode；
2. **选关键帧**：`t_pre = t_grasp - 5`、`t_grasp`、`t_post = t_grasp + 5`、`t_goal`；
   - `t_grasp`：夹爪从开（>3.0）到闭（<1.0）的第一帧；用 `observation.state.*_gripper` 的差分和动作确认；
3. **人工点击**：在 `t_pre` 点 grasp part，在 `t_post`/`t_goal` 点 target part；每任务 2–3 个部位；
4. **SAM 3 跟踪**：用 point/box exemplar 得到首帧 mask，用 video predictor 传播到整条 episode；
5. **跨 episode 初始化**：把 canonical mask 作为 exemplar，对同任务其他 episode 的首帧做检测/跟踪；失败则用文本 prompt（"cup handle"）兜底；
6. **多视图校验**：
   - 头左/右：用双目视差/深度把 mask 抬到 3D，检查左右一致性；
   - 腕部：用近景 mask 检查接触点是否落在部位上；
   - 夹爪：用 `state_d435` + 内参把夹爪投影到头图，检查 `t_grasp` 时夹爪是否在 grasp part 附近；
7. **置信度**：`c = w_s·mask_stability + w_v·multi_view_consistency + w_g·gripper_part_distance`；低于阈值标为 `low_confidence`，不进入 part 级训练/评测。

**规模估算**：

- 32 任务 × 2–3 部位 = 64–96 次点击；
- 33,276 episodes × 平均约 550 帧 = 18.28M 帧；SAM 3 视频跟踪离线跑，按每 GPU 每天约 2–4k episodes 估算，需 8–16 GPU·天（取决于分辨率/跟踪设置）；
- 人工抽检：每任务 10 episodes，32×10=320 条，检查 mask IoU 和接触点命中。

#### 3.1.3 反事实变换

**位置**：

- 用 part mask + 双目深度把目标物体抬到 3D，平移 ΔT；
- 把原区域 inpaint（SAM 3 mask + 背景纹理）；
- 把 ground-truth action 用同一 ΔT 变换；
- 指标：`EQ_pos = || a_pred(T·o) - T·a_gt(o) ||`，以及预测接触点是否落在平移后的 part mask。

**干扰物**：

- 从另一任务取一个物体 mask，按桌子平面尺度/光照合成到目标附近；
- 确保不遮挡 target part；
- 指标：接触点/动作偏移 `DI`。

**背景**：

- 用所有物体 mask 的补集做背景 mask，替换为另一任务的桌面背景；
- 指标：动作偏移 `BI`。

**未见物品**：

- 换同类不同外观的物体（颜色/形状/材质），官方轴的定义是「同一类别、不同外观」；
- 用 SAM 3 分割新物体，人工/自动标新物体的功能部位；
- 指标：`UOT` = 新物体上的 PGA / 原物体 PGA。

**人为干扰**：

- 在 t 与 t+1 之间把 target part 平移 Δ；
- 用 inpaint 补原位置；
- 指标：`HIR` = 策略重新对准新位置所需帧数；超过 N 帧算失败。

> 这些反事实图像不是照片级真实，**只用于诊断**，不直接当训练数据。若要用作训练（SEM-GAP），必须过滤合成伪影并做真机小样本验证。

#### 3.1.4 与单任务通道校准

官方有不计分单任务测试通道。选 5 个任务（建议 HangCup、ZipUp、Unlock、PlugInEthernet、StackBowls），每个跑 20 次：

- 记录真实成功率、平均步骤分；
- 对同一批 episode 算 PART-SCORE；
- 用 Spearman/Pearson 相关校准；ρ≥0.7 才把 PART-SCORE 用于选任务；ρ<0.5 只用于分诊。

### 3.2 AFFORD-HEAD：把 part 标签变成在线单模型先验

#### 3.2.1 基座

官方 `unifolm-wla` / `UnifoLM-WLA-1.0-Base`：约 6B，VLM 冻结，只训 DiT action head + robot-state projector，单张 24GB 可跑。我们不改基座架构，只加辅助目标/轻量头。

#### 3.2.2 两种实现

**A1 隐式对齐（AffordVLA 路线，主选）**

```text
训练：
  z_vla = VLA_visual_tokens(o, l)          # 中间层视觉 token
  z_sam = SAM3_part_features(I, M_P)       # 离线 teacher，part 区域 pooled 特征
  L_align = 1 - cos( Proj(z_vla), z_sam )  # Proj 只在训练时用
  L = L_action + λ1·L_align + λ2·L_smooth

推理：
  只跑 VLA；Proj 和 SAM 3 丢弃；零额外延迟。
```

优点：

- 推理零额外模块，最符合「单模型」；
- AffordVLA 报告隐式对齐优于显式 mask 注入（显式注入会拖慢推理）；
- 不需要改 action head 接口。

风险：

- 对齐目标可能过于抽象，part 定位不可视化；
- SAM 3 特征维度/层选择敏感；
- 如果 VLA 视觉 token 分辨率太低，细部位（拉链头、钥匙孔）对齐不上。

**A2 显式热图（MAST-VLA 路线，备选）**

```text
训练：
  H_part = PartHead(z_vla)                 # 轻量 deconv/MLP，输出 K 个 part 热图
  L_part = BCE(H_part, M_P) + Dice(H_part, M_P)
  L = L_action + λ1·L_part + λ2·L_smooth

推理：
  H_part 作为 action head 的空间先验（patch-level bias / 额外 token）；
  仍是同一个 checkpoint，单次前向。
```

优点：

- 可解释、可可视化，便于调试「抓错部位」；
- 可以直接把热图峰值作为 PART-SERVO 的目标；
- MAST-VLA 证明 affordance heatmap 作为轨迹先验有效。

风险：

- 多一个头，延迟 +几 ms；需要控制分辨率/频率；
- 热图监督噪声会传到 action head；
- 透明/反光物体的 mask 噪声大。

**门控**：

- 先跑 A1；若 UOT/DI 提升 ≥10pp 且 clean 不回归，选 A1；
- 若 A1 不升，跑 A2；若 A2 升但延迟 p99 增加 >10ms，降到 A1 或只用 C1；
- 若两者都不升，退回 C1（只用 part 标签做 PART-SERVO，不改模型）。

#### 3.2.3 训练数据

- 33k episodes 的关键帧：`t_pre`、`t_grasp`、`t_post`、`t_goal`；
- 每任务平衡采样，避免 ColorArrangement（1533 eps）压倒 HangCup（1043 eps）；
- 语言用 5 条同义指令随机采样；
- 相机随机化：由于头双目标定逐数据集不同，训练时对图像做裁剪/缩放/内参扰动，避免模型死记某个 fx；
- 反事实增强（SEM-GAP，可选）：背景替换、干扰物合成、物体替换；只在高置信度 mask 上用。

#### 3.2.4 合规论证

- A1：推理只有一个 VLA checkpoint；SAM 3/Proj 只在训练时出现；
- A2：PartHead 是同一 checkpoint 的一部分；单次前向；
- C1 兜底：完全不改模型，只用 part 标签做 PART-SERVO 的确定性目标；
- 三种模式都不在评测时加载第二个模型；如果规则对「模型」定义有疑问，提前向主办方书面确认。

### 3.3 PART-SERVO：把 CHUNK-SERVO 的目标换成功能部位

#### 3.3.1 离线相对目标

```text
T_part_ee*(k) = T_base_part(k)^-1 · T_base_ee(k)
```

对演示的每个关键帧 k，算 part→EE 的相对位姿。检索时按 part 类别/语言/初始相对位姿选 top-K，做加权平均（SE(3) 用测地线平均）。

#### 3.3.2 在线伺服

```text
输入：当前观测 o_t、part 目标 T_base_part(t)、相对目标 T_part_ee*
输出：EE 目标 T_base_ee^d(t) = T_base_part(t) · T_part_ee*
误差：e(t) = log( T_base_ee(t)^-1 · T_base_ee^d(t) )
```

- 远距离（>5 cm）：头部双目 + part 3D 质心，PBVS；
- 近距离（≤5 cm）：腕部 part 掩码，2D IBVS（fx 已知）；
- 接触段：法向缩幅 0.2–0.5，切向保留；夹爪闭合后切到力/位置保持（无 force 传感器，用位置残差）；
- 置信度低：回退 object 级 → 回退 VLA 开环；
- 人为干扰：part 掩码丢失/位移 > 阈值 → 重新检测/跟踪 → 更新 `T_base_part` → 恢复。

#### 3.3.3 与 CHUNK-SERVO 的接口

```text
在本方案中，VLA 每 30 步输出一个 chunk：
  - 前 25 步：开环执行（保留 VLA 的意图）
  - 后 5 步：PART-SERVO 用 part 目标修正（只改末端 6D，不改夹爪开合）
  - 接触检测触发：提前进入 PART-SERVO
```

这与上一轮 CHUNK-SERVO 的 30→5 设计兼容；区别是伺服目标从 `T_base_target`（物体/受器）换成 `T_base_part`（功能部位）。

def get_action(obs, meta):

## 4. 推导与细节

### 4.1 从像素到 3D 部位

头部双目（rectified）视差：

```text
d = u_L - u_R
Z = f · B / d
X = (u_L - c_x) · Z / f
Y = (v_L - c_y) · Z / f
```

其中 `f`、`B`、`c_x`、`c_y` **逐数据集**从 `camera_params.head_stereo` 读取；HangCup 的 `f≈282.37`、`B≈58.25 mm`，ZipUp 的 `f≈186.03`、`B≈54.84 mm`，Unlock 的 `f≈296.15`、`B≈63.24 mm`。这直接说明为什么不能用一个全局标定。

腕部单目（无深度）只能给 2D；3D 需要：

- 手眼标定 `T_ee_wrist`（数据未给，需自标）；
- 或头部双目把 part 3D 点投影到腕部做对应；
- 或假设 part 在桌面上，用平面先验 + 腕部 ray 求交。

### 4.2 等变性/不变性为什么是有效诊断

如果策略学到了「物体移动 Δ，动作也移动 Δ」，那么它在位置轴上线；如果它只学到了「看到杯子就抓图像中心」，位置轴会崩。`EQ_pos` 直接测这个性质，不需要闭环。

同理：

- `DI` 测策略是否被干扰物吸走；
- `BI` 测策略是否依赖背景纹理；
- `UOT` 测策略是否依赖实例外观；
- `HIR` 测策略是否能从 part 位移中恢复。

这些性质与官方五轴一一对应，但可以在离线大规模跑，成本远低于 320 trials。

### 4.3 标签噪声与置信度

SAM 3 不是完美的：

- 透明试管、反光杯、细拉链头、钥匙孔可能跟踪失败；
- 腕部近景可能有运动模糊；
- 遮挡/夹爪遮挡会导致 mask 断裂。

置信度：

```text
c = 0.4·mask_stability
  + 0.3·multi_view_consistency
  + 0.2·gripper_part_distance_score
  + 0.1·language_part_match
```

- `mask_stability`：相邻帧 mask IoU 的均值；
- `multi_view_consistency`：头左/右 3D 质心距离；
- `gripper_part_distance_score`：`t_grasp` 时夹爪投影到 grasp part 的距离；
- `language_part_match`：语言里的 part 词与 ontology 的匹配。

低置信度任务降级为 object 级，不进入 part 级训练；在 PART-BENCH 里标为 `diagnostic-only`。

### 4.4 单模型合规的三种模式

| 模式 | 在线模型数 | SAM 3 在线 | 改动 | 风险 |
|---|---:|---|---|---|
| C1 离线标签 | 1 | 否 | 只改 PART-SERVO/评测 | 最低；模型不变 |
| C2 确定性控制器 | 1 | 否 | 加 part 伺服 | 低；控制器不是学习模型 |
| C3 同 checkpoint 辅助头 | 1 | 否 | AFFORD-HEAD A1/A2 | 中；需证明辅助头属于同一模型 |
| X 在线分割 | 2 | 是 | SAM 3 + VLA | 高；违反单模型/延迟 |

本方案只走 C1/C2/C3；X 明确剪掉。

## 6. 竞赛策略

### 6.1 任务组合

- **先打 H 档 21 个**：part 级收益最大；但不要一次全上，先选 5 个做 A/B；
- **5 个首发建议**：HangCup（挂/钩）、ZipUp（拉链头）、Unlock（钥匙孔）、PlugInEthernet（RJ45 卡扣）、StackBowls（碗沿）。覆盖抓取、插入、 articulated、堆叠四类；
- **M 档 9 个**：part 标签用于诊断，不优先改模型；
- **L 档 2 个**（FruitCollection/FruitSorting）：保留 VLA 基线，不做 part 伺服；
- **FoldTowel**：机器人型号 `unitree_g1_8520` 不同，且可变形；单独监控，不作为 part 收益证据。

### 6.2 预期增益（C，设计目标，不是承诺）

官方总分是 32 任务平均成功率。若 AFFORD-HEAD 让 H 档任务提升 Δ：

| 情景 | 提升任务数 | 单任务 Δ | 全局 Δ |
|---|---:|---:|---:|
| 保守 | 5 | +10pp | +1.6pp |
| 中性 | 10 | +10pp | +3.1pp |
| 乐观 | 21 | +5pp | +3.3pp |
| 强 | 21 | +10pp | +6.6pp |
| 叠加人为干扰轴 | — | +10pp on 20% trials | +2.0pp |

这些是**上限估算**；实际会被标签噪声、相机域偏移、延迟、长尾任务吃掉。G2/G4 校准后才更新预期。

### 6.3 提交节奏

1. 先交 C1（只加 PART-SERVO，模型不变）作为安全基线；
2. 再交 C3-A1（隐式对齐）；如果离线/真机都升，保留；
3. A2 只作为 A1 失败后的备选；
4. 每次提交保留回滚点；不把未过 G4 的模型送全量。

### 6.4 与官方榜单的关系

- 不追榜单数字；当前不可复核；
- 用单任务通道做校准锚点；
- 用 PART-BENCH 做日常迭代；
- 全量 32×10 只在 G4/G6 通过后跑。

## 8. 风险与合规

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| SAM 3 标签噪声 | 高 | part 指标/训练被污染 | 置信度门控；低置信度降级 object；人工抽检 |
| 透明/反光/细部位失败 | 高 | 部分任务不可用 | 腕部近景；深度边缘；任务降级 |
| 相机域偏移 | 高 | 模型跨任务退化 | 逐数据集内参；相机随机化；part 相对表示 |
| 推理无 camera_info | 高 | 3D 伺服尺度错 | 用图像统计/任务先验；对尺度不敏感的相对目标 |
| 手眼外参缺失 | 中 | 腕部 3D 不可用 | 头部双目兜底；一次手眼标定 |
| AFFORD-HEAD 破坏原策略 | 中 | clean 回归 | 冻结 VLM；低学习率；KL/正则；早停 |
| 延迟超预算 | 中 | 评测失败 | A1 零额外；A2 降频；p99 监控 |
| 单模型规则争议 | 中 | 合规风险 | C1 兜底；提前书面确认；SAM3 离线 |
| 代理指标与真机不相关 | 中 | 选错任务 | G2 校准；ρ<0.5 只做诊断 |
| 全量 320 trials 不稳定 | 中 | 分数波动 | N 端口隔离；reset 测试；干跑 |
| 任务名/数据映射错 | 低 | 训练错任务 | 以 HF collection 32 名为准；自动校验 |

**合规底线**：

1. 评测时只加载一个模型 checkpoint；
2. SAM 3 只在离线标注/训练时用；
3. PART-SERVO 是确定性控制器，不是第二个学习模型；
4. 不按任务切换模型/权重（包括 LoRA 路由，除非确认规则允许）；
5. 提交前做「断网 + 单进程 + 单 checkpoint」审查。
