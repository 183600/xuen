# 第 2 轮（UniBot 线 · 灵感循环第 1 轮；本轮灵感：「中间件」×「主动交互」）· UniBot-PACT：主动式契约中间件

> **承接声明**：本线承接第 1 轮 UniBot-SAGE（接地层 / 技能层 / 适应层 / 工程层；定义 U1–U12、引理 L1–L7、实验 E601–E618）。本轮不推倒重来，而是**重写"工程层"的认识论地位**：把"避免 bug 的胶水"升级为"策略与评测器之间的可编程契约层"，并在其上做信息增益驱动的主动交互。
> **一句话**：第 1 轮问"抓住没有"；本轮问"**我的动作到底被怎么执行、我该主动做什么去搞清楚**"。

## 0. 本轮定位与情报纪律

- **不新增外部事实**：沿用第 1 轮已核实的接口与榜单事实（来源见产物区 §10）；本轮只做重新解释与推论。
- 第 1 轮把接口当作"约束"；本轮把接口当作"**可观测、可辨识、可协商的随机系统**"。
- 关键保留意见不变：`leaderboard_data.json` 是 teaser / 占位表，只用于结构参照，不用于调参。

## 1. 直觉与动机

### 灵感 1 ·「中间件」→ 接口不是边界，而是唯一的"可编程观测面"

**直觉解释**：分布式系统里，中间件存在的理由从来不是"把两个端点粘起来"，而是因为端点**异构、不可靠、契约不完整**。中间件做四件事：**抽象异构**（obs / action 语义归一）、**调度资源**（N 端口共享一个 GPU 后端）、**隔离故障**（一个 session 崩不拖垮其他）、**可观测**（延迟、重试、异常）。
UniBot 的提交接口恰好是这样一个端点：websockets + msgpack + numpy、N 个连续端口、每端口独立 episode、chunk 语义未公开、`image_resize` 在评测端做、token 两处校验、官方明确采集延迟与动作规律性。第 1 轮把这些当"工程注意事项"；从中间件视角看，它们其实是**唯一能在真机上读到的、关于"执行语义"的信号源**。

**严谨表述**：把策略与评测器的交互建模为一个**部分可观测的契约系统**。存在评测器语义参数 `θ_env`（chunk 是逐步执行还是整块插值、动作是绝对还是增量、pivot 是否被跟踪、观测时间戳如何对齐、每步延迟分布），策略看不到 `θ_env`，只能通过自己下发的动作与收到的观测 / 延迟 / 拒绝事件推断它。中间件的职责是维护 `b_t(θ_env)` 并据此**适配动作语义**，而不是假设 `θ_env` 已知。

### 灵感 2 ·「主动交互」→ 观测不是免费的，但在这个计分函数下"时间几乎免费"

**直觉解释**：反应式策略把观测当作外生、免费、与动作无关。但真实具身系统里，**观测是动作的函数**：移动手腕才能看清抓握，轻抬才能确认物体是否随动，推开遮挡物才能看见目标。POMDP 理论里这叫**对偶控制（dual control）**：动作同时改变状态和信念，最优策略会主动做"为了知道"的动作。
UniBot 的计分给了我们一个罕见的不对称：第 1 轮从 teaser 榜算出任务内 `corr(duration, success) ≈ −0.011`、episode 43.7–45.2 s，且 `step_score ≈ 1.337·success + 0.09`。这意味着**"多花几百毫秒去获取信息"在计分上几乎不收费**，只要它不把终态成功搞砸。换句话说，**评分函数在隐式补贴主动感知**。这是本轮最核心的杠杆：把"时间预算"换成"信息预算"。

**严谨表述**：在只有终态成功计分、时间无独立惩罚的设定下，一个探测动作 `a_probe` 的期望收益为
`VOI(a_probe) = E[Δsuccess | a_probe] − λ_risk·E[damage | a_probe] − λ_time·E[Δt]`，
其中 `λ_time ≈ 0`（只要不触发超时），`λ_risk` 由不可逆扰动（碰倒、卡死、把目标推远）决定。因此**只要探测是风险有界且可恢复的，它的 VOI 门槛极低**。这与第 1 轮"抓握误判不对称"正好互补：第 1 轮担心"漏判"，本轮用主动探测把"漏判"变成"可观测"。

### 合成

**中间件提供"安全地主动"的基础设施；主动交互提供"中间件为什么值得做"的决策论理由。**
- 没有主动交互的中间件 = 只会记日志的管道；
- 没有中间件的主动交互 = 危险的、不可审计的乱动；
- 两者合起来 = **PACT（Proactive Adaptive Contract middleware）**：一个能辨识契约、调度探测、执行降级、产出审计的运行时。

## 2. 从第 1 轮数据能读出什么（不新增事实，只做推论）

| 第 1 轮事实 | 本轮推论 |
|---|---|
| 时间与成功几乎无关（任务内 corr ≈ −0.011） | 时间预算可换成信息预算；探测的 `λ_time` 近似为 0 |
| step_score 与 success 近共线（R²=0.9955） | 只有终态成功计分 ⇒ 探测只要不降低成功率就"免费" |
| 最难任务集中在插入 / 旋转 / 细粒度（Plug In Ethernet 17.7、Unlock 20.1、Open Pill Bottle 22.7） | 这些正是"执行语义 + 接触状态"最不透明的任务 ⇒ 主动探测收益最高 |
| 跨任务 Kendall τ ≈ 0.064 | 主动探测是**任务无关的共享机制**，不需要 32 个专用策略 |
| 接口有 N 端口、chunk、延迟监测 | 中间件是唯一能同时优化"并发、语义、审计"的位置 |

**一个粗略的信息经济学估算**：若一个 test-lift 探测花 0.4 s（≈0.9% episode），把某难任务的抓握成功率从 20% 提到 24%（绝对 +4 个点），则期望收益 ≈ +4 分；而它带来的超时风险 < 0.9% × 失败代价。只要探测的不可逆扰动概率 < 10%，VOI 就为正。这个估算说明：**在榜首不到 30% 的区间里，信息比时间贵得多**。

## 3. 研究问题（本轮版）

- **Q1（契约可辨识性）**：在只允许使用已声明动作空间、且不读取评测器私有信息的前提下，能否用少量"任务有用"的探测动作，把 `θ_env` 辨识到**决策等价类**（足以决定是否启用 chunk 缝合、用 joint 还是 ee、是否发 pivot）？可辨识的下界是什么？
- **Q2（探测调度）**：如何把"试提 / 转腕 / 轻推 / 清障"建模成带风险预算的探测集合，并用 VOI 在 episode 内在线调度？探测与任务推进如何共享同一条动作流而不被判定为"不规则交互"？
- **Q3（中间件架构）**：N 端口共享后端时，连续批处理（continuous batching）对 per-step 延迟 p99 的影响是什么？如何在精度相位给关键 session 优先权，同时保证公平与隔离？
- **Q4（主动场景整形）**：在 5 类泛化场景（尤其干扰物 / 未见物品）里，"先把场景变得更可操作"（移开遮挡、转正物体、清出通道）是否比"直接抓目标"更优？其安全与合规边界在哪里？
- **Q5（可信度）**：主动探测会不会让动作统计变得"过于规律 / 过于异常"，从而撞上官方可信度审核？如何让探测**既有效又可审计**？

## 4. 设计原则

- **P1 终态成功是唯一货币**：任何探测必须能写成"提高终态成功"的因果链；否则不做。
- **P2 不确定性显式化并配探针**：抓握、接触、相位、契约、延迟五类不确定性，每一类都要有对应的观测或探测。
- **P3 中间件即契约层**：观测适配、动作适配、会话隔离、调度、降级、审计六件事必须在同一层完成，且**无隐藏副作用**。
- **P4 探测风险有界且可恢复**：每个探测必须有恢复动作、最大次数、禁区；不可逆动作（可能碰倒目标 / 卡死夹爪）默认禁止。
- **P5 合规优先**：只用已声明动作空间；不读私有信息；不硬编码任务；不利用未声明执行语义；探测必须"任务有用"而非"评测器套利"。
- **P6 单模型、单 API**：中间件在模型之外，不改变"单 checkpoint 通才"的合规叙述。

## 5. 架构：四层 + 一个数字孪生

```
[评测器 N ports] ⇄ [L1 PACT 中间件] ⇄ [L0 SAGE 策略]
                         │
        ┌────────────────┼─────────────────┐
        ▼                ▼                 ▼
  L2 契约估计器     L3 主动交互调度器   L4 安全/合规包络
        │                │                 │
        └──────────► L5 ReplayTwin（离线数字孪生/回放）◄──┘
```

- **L0 SAGE**：第 1 轮策略（skill token MoE + grasp verifier + context adapter）。本轮不改主干。
- **L1 PACT**：obs adapter（键名 / 叠帧 / resize 语义）、action adapter（chunk 缝合 / 空间转换 / 限幅）、session mesh（端口隔离 / 批处理 / 背压）、telemetry（延迟 / jerk / 拒绝）、degradation controller。
- **L2 契约估计器**：维护 `b_t(θ_env)`，用探测与正常交互的"动作 → 观测 / 延迟"配对更新。
- **L3 主动交互调度器**：在"推进 / 探测 / 恢复 / 整形"四类动作间做 VOI 选择。
- **L4 安全 / 合规包络**：风险预算、动作边界、黑名单、审计证书。
- **L5 ReplayTwin**：用官方 client 复刻评测器语义的离线回放，用于预注册实验与回归测试（第 1 轮 IP-03 步骤①的升级版）。

## 6. MVP 与退化链

**MVP = PACT 核心（L1）+ 契约探针（L2 的保守子集）+ test-lift 探针（L3）+ ReplayTwin（L5）+ 第 1 轮基线。**
理由：L1 是所有主动行为的安全底座；test-lift 是收益最高、最易验证的探针；ReplayTwin 让其余组件能在真机时段外迭代。

**退化链（任一环节不可用 ⇒ 回退而非漂移）**：
- **D0** 契约估计置信度低 ⇒ 假设"最保守语义"（不缝合、不改 chunk、不依赖 pivot）；
- **D1** 探测风险预算耗尽 ⇒ 停止探测，退回第 1 轮开环策略；
- **D2** 批处理导致 p99 超预算 ⇒ 关闭批处理，单 session 直通；
- **D3** 审计发现"不规则" ⇒ 关闭主动整形，只保留 test-lift；
- **D4** 中间件整体故障 ⇒ 直接透传（passthrough）到 L0，保证最小可提交。

## 7. 预期贡献

1. **把 UniBot 接口形式化为"部分可观测契约"**，给出 `θ_env` 的可辨识性条件与最小探测集——这是全赛道可复用的公共品。
2. **提出风险有界的主动交互调度**（VOI + 恢复动作 + 最大次数），把第 1 轮的"抓握确认"统一为"主动探测"的一个特例。
3. **给出多端口中间件的延迟 / 隔离 / 批处理设计**，并用队列论给出 p99 上界；交付可审计看板。
4. **量化"评分函数对信息的补贴"**：在时间无独立惩罚的设定下，证明探测的 VOI 门槛极低，并给出"何时不该探测"的反例边界。
5. **主动场景整形的可行性边界**：在干扰物 / 未见物品场景中，给出"整形收益 > 扰动风险"的判据。

## 8. 本轮最大风险

**一句话**：主动交互会把策略从"在训练分布上执行"变成"主动改变分布"——探测与场景整形可能把可恢复的失败变成不可逆的失败（碰倒目标、卡死夹爪、把物体推到够不到的地方），而中间件的批处理与语义适配又可能引入新的时序伪影，被评测端判定为"不规则交互"；也就是说，**我们为了解决不确定性而引入的动作，本身就是新的不确定性来源**。

## 9. 下一轮计划

- **深化**：把 L2 的契约估计从离散假设检验升级为贝叶斯信念 + 主动学习；把 L3 的 VOI 从启发式升级为带风险约束的 POMDP 近似。
- **修剪**：若 ReplayTwin 与真机的语义一致性 < 0.8（动作级），则砍掉一切依赖 ReplayTwin 的契约结论，只保留"保守语义 + test-lift"。
- **保留**：L1（中间件底座）、test-lift、D4（passthrough）在任何情况下不砍。

## 0. 本轮结论摘要

**一句话路线**：把第 1 轮的"工程层"重写为 **PACT 中间件**，在其上做 **VOI 驱动的主动交互**。核心命题：**在只有终态成功计分、时间几乎免费的设定下，信息获取的期望收益远高于其时间成本，但必须以风险有界、可恢复、可审计的方式获取。**

## 2. 创新点详述

### IP-09 · ContractProbe 契约探针（P0）

- **动机**：`θ_env` 未知。若错误假设"chunk 逐步执行 / 不插值 / 动作绝对 / pivot 被跟踪"，缝合、空间转换、姿态先验都会产生系统性误差；而这些误差恰好集中在最难的插入 / 旋转任务。
- **与现有方案的差异**：第 1 轮 IP-03 的做法是"先用官方 client 复刻，再决定是否启用"；本轮把复刻升级为**在线贝叶斯辨识**：不追求辨识完整 `θ_env`，只辨识**决策等价类** `~_D`（对中间件配置选择有影响的那一 partition）。
- **探测集**（全部在已声明动作空间内，且尽量嵌入任务动作）：
  1. **Reference-frame probe**：在接近段叠加一个 2 mm 级横向微动，观察 EE / 视觉响应方向；
  2. **Chunk-semantics probe**：在自由空间下发一个末端为"保持"的短 chunk，观察是逐步执行还是整块插值；
  3. **Latency probe**：无需额外动作，记录请求 / 响应时间戳，估计 per-step 延迟分布；
  4. **Pivot probe**：静止时下发小幅 `action.pivot`，观察 `lower_body` / 基座是否响应；
  5. **Interpolation probe**：仅在自由空间、远离物体处制造一个受控 C1 不连续，观察 jerk 响应（风险最高，默认关闭）。
- **技术可行性**：高。全部信号在接口内；辨识用离散贝叶斯更新即可，算力可忽略。
- **所需资源**：官方 client；算力极小；无需新数据。
- **落地步骤**：①定义 `Θ` 与 `~_D`；②在 ReplayTwin 里枚举语义模式并生成观测分布；③设计嵌入任务动作的探测序列；④在线更新 `b_t(θ)`；⑤按 `b_t` 选择中间件配置；⑥合规审查（探测是否可被解释为正常动作）。
- **风险**：①探测被判定为"不规则交互" ⇒ 幅度受限 + 嵌入任务动作 + TrustShield；②辨识错 ⇒ 保守回退 D0；③`~_D` 划分过粗 ⇒ 无法区分关键语义 ⇒ 补充任务后验校准。

### IP-10 · VOIScheduler 主动交互调度（P0）

- **动机**：主动交互是对偶控制问题：动作同时改变任务状态与信念。需要决定"何时推进、何时探测、何时恢复、何时整形"。
- **与现有方案的差异**：第 1 轮 IP-02 只在"抓握置信度低"时被动介入；本轮把介入升级为**主动选择**：在每个决策点比较四类候选动作的期望终态成功。
- **候选动作**：`A_task`（策略原始推进）、`A_probe`（test-lift / wrist-scan / micro-wiggle）、`A_recover`（重抓 / 换原语）、`A_shape`（场景整形，见 IP-12）。
- **技术可行性**：中–高。在线用轻量价值模型 + 保守 VOI；离线用 ReplayTwin 标定价值模型与风险等级。
- **所需资源**：小算力；一个价值头（可用第 1 轮主干特征）；无新数据。
- **落地步骤**：①定义风险等级（可逆 / 半可逆 / 不可逆）；②训练 / 标定价值模型 `V(b, a)`；③实现风险预算 `ρ_t` 与最大探测次数；④在 ReplayTwin 上做离线策略评估；⑤真机 A/B（探测开 / 关）。
- **风险**：①价值模型偏差导致过度探测 ⇒ 最大次数 + 风险预算 + 只在难任务启用；②探测扰动场景 ⇒ 幅度 / 时长上限；③VOI 估计不准 ⇒ 保守阈值 + 回退。

### IP-11 · SessionMesh 多端口中间件（P0）

- **动机**：评测在 N 台真机上随机顺序执行，必须暴露连续端口 8765…8765+N−1，每端口独立跑完整交互；共享后端时并发安全与状态隔离是硬约束，延迟与动作规律性还会被用于可信度评估。
- **与现有方案的差异**：常见做法是"每个端口起一个进程"或"简单串行"；本轮做**共享后端 + N 个轻量前端 + 连续批处理 + 优先级调度 + 背压**，并给出延迟上界。
- **设计要点**：
  1. **会话隔离**：`Session(port, history, b_t, budget)`；`reset(port)` 只清该会话；
  2. **连续批处理**：在 `w` ms 窗口内聚合 `get_action` 请求，批处理主干前向；
  3. **精度优先**：抓握 / 对齐相位跳过批处理或提高优先级；
  4. **背压**：队列深度超阈值 ⇒ 降级（小模型 / 缓存动作 / passthrough）；
  5. **延迟 SLO**：p99 ≤ τ；用批服务排队模型给出上界。
- **技术可行性**：高（工程活，但需严格测试）。
- **所需资源**：官方 client；小算力；并发压测脚本。
- **落地步骤**：①复刻官方 server/client；②实现会话隔离与批处理；③压测 N 端口 × 8 h；④注入故障（断连、超时、重复 reset）验证隔离；⑤导出延迟 / 吞吐 / 降级看板。
- **风险**：①批处理抬高部分 session 延迟 ⇒ 精度相位优先 + 窗口自适应；②优先级饿死其他 session ⇒ 公平配额；③状态串扰 ⇒ 自动化体检脚本。

### IP-12 · SceneShaping 主动场景整形（P1）

- **动机**：5 类泛化场景含干扰物 / 遮挡 / 未见物品；有时"先把场景变得更可操作"比"直接抓目标"更省事、更稳。
- **与现有方案的差异**：第 1 轮 IP-02 的非抓取原语用于"抓不住时的退路"；本轮把它升级为**主动的场景预处理**：移开遮挡、转正物体、分离嵌套物、清出通道。
- **技术可行性**：中。原语可用第 1 轮的数据检索 + 少量真机试错；难点是判断"整形是否值得"与"是否违反任务语义"。
- **所需资源**：小算力；少量真机时段；规则确认。
- **落地步骤**：①定义整形算子与前后条件；②训练 / 规则化"是否值得整形"的判据；③在干扰物场景做 A/B；④合规确认（是否允许移动非目标物）。
- **风险**：①移动非目标物可能违反任务约束 ⇒ 默认只动"明确遮挡且非目标"的物体；②碰倒 / 推远目标 ⇒ 只对非目标物操作 + 低速低力；③被判定为"改变任务" ⇒ 先问规则再启用。

### IP-13 · TrustShield 可信度包络（P1）

- **动机**：官方明确会采集 per-step 延迟及其波动、返回动作的统计规律性，并可能据此评估可信度。主动探测若显得"规律得像脚本"或"异常得像故障"，都会伤害可信度。
- **与现有方案的差异**：第 1 轮 IP-08 只是"审计 + 限幅"；本轮把可信度变成**主动行为的约束条件**：探测必须满足平滑性、速率、任务有用性三类约束。
- **设计要点**：
  1. **速率约束**：`probe_rate ≤ r_max`；
  2. **平滑约束**：`jerk ≤ J_max`，探测动作从同一动作分布采样，不注入人工噪声；
  3. **任务有用性**：每个探测记录 VOI 估计与理由，形成审计证书；
  4. **异常检测**：离群动作自动限幅，但不做"拟人化"噪声。
- **技术可行性**：高。
- **所需资源**：极小算力。
- **落地步骤**：①埋点采集延迟 / jerk / 探测率；②定义可信度分数与阈值；③离线回放验证；④真机审计报告。
- **风险**：①约束过紧 ⇒ 探测收益下降；②约束过松 ⇒ 被判定 irregular；③"任务有用"难自证 ⇒ 用 VOI 日志 + 回放。

### IP-14 · ReplayTwin 语义数字孪生（P0）

- **动机**：真机时段稀缺，且评测器语义未公开；没有离线孪生，契约辨识与主动调度都无法预注册、无法回归。
- **与现有方案的差异**：第 1 轮 IP-06 是"代理评测 + 六因子分解"（评成功率）；本轮 IP-14 是"语义孪生"（评**执行语义**）：可配置不同 `θ_env` 模式（逐步 / 插值 / 绝对 / 增量 / pivot 跟踪 / 延迟分布），回放同一动作流并比较结果。
- **技术可行性**：中–高。官方 client 可复刻；难点是与真机对齐。
- **所需资源**：官方 client；中等算力；少量真机标定。
- **落地步骤**：①复刻 server/client 与 chunk 执行；②实现语义模式开关；③用真机少量样本标定一致率；④接入 IP-09/10 的离线评估。
- **风险**：①孪生与真机不一致 ⇒ 预注册"一致率 <0.8 则砍掉依赖孪生的契约结论"；②过度拟合孪生 ⇒ 只在真机 A/B 做最终决策。

### IP-15 · TestLift 抓握主动确认（P0）

- **动机**：第 1 轮 IP-02 的抓握判定依赖被动信号（腕部几何 + 夹爪标量 + EE 速度）；本轮增加一个**主动证据**：轻抬后看物体是否随动。
- **与现有方案的差异**：从"被动推断"升级为"主动实验"：`grasp → lift 1–2 cm over 0.3–0.5 s → check follow → 决策`。
- **技术可行性**：高。动作在已声明空间内；判定用腕部帧位移 + EE 速度一致性 + 夹爪闭合。
- **所需资源**：极小算力；无新数据。
- **落地步骤**：①实现状态机；②定义"随动"判据与阈值；③与被动判定融合（贝叶斯）；④难任务 A/B；⑤失败恢复（重抓 / 换原语）。
- **风险**：①轻抬可能掉落 / 碰撞 ⇒ 限高、限速、上方无障碍检查；②误判随动 ⇒ 多信号融合 + 置信度门控；③增加时间 ⇒ 时间几乎免费，但仍设最大次数。

## 3. 符号与定义（U13–U24）

| 符号 | 含义 |
|---|---|
| `θ_env` | 评测器 / 本体执行语义参数（chunk 执行、参考系、插值、pivot、延迟） |
| `b_t(θ)` | 契约信念：`P(θ_env = θ | h_t)` |
| `~_D` | 决策等价：两个 `θ` 诱导相同最优中间件配置 |
| `A_probe` | 探测动作集 {test_lift, wrist_scan, micro_wiggle, free_space_discontinuity, pivot_nudge} |
| `VOI(a)` | 动作 `a` 相对纯任务动作的期望终态成功增益 |
| `ρ_t` | 剩余不可逆风险预算 |
| `S_i` | 第 i 个端口的会话状态（历史、信念、预算） |
| `w` | 批处理聚合窗口 |
| `s` | 场景整形算子 |
| `T` | 可信度分数（延迟稳定性、平滑性、探测率、任务有用性） |
| `D_k` | 退化级别（D0…D4） |
| `C` | 审计证书 |

**定义 U13（契约参数）** `θ_env = (θ_chunk, θ_frame, θ_interp, θ_pivot, θ_lat) ∈ Θ`，其中 `θ_chunk` 为 chunk 执行模式，`θ_frame` 为动作参考系，`θ_interp` 为插值方式，`θ_pivot` 为 pivot 是否跟踪，`θ_lat` 为延迟分布参数。

**定义 U14（契约信念）** `b_t(θ) = P(θ | h_t)`，`h_t = (a_{1:t}, o_{1:t}, Δt_{1:t})`；用贝叶斯更新
`b_{t+1}(θ) ∝ b_t(θ)·P(o_{t+1}, Δt_{t+1} | θ, a_{t+1})`。

**定义 U15（决策等价）** `θ_1 ~_D θ_2 ⇔ argmax_{m∈M} E[success | θ_1, m] = argmax_{m∈M} E[success | θ_2, m]`，`M` 为中间件配置集合（是否缝合、chunk 长度、joint/ee、是否发 pivot）。

**定义 U16（探测集）** `A_probe = {a_testlift, a_wristscan, a_wiggle, a_disc, a_pivot}`，每个 `a` 带风险等级 `risk(a) ∈ {rev, semi, irrev}`、时长 `Δt(a)`、恢复动作 `rec(a)`。

**定义 U17（VOI）** `VOI(a) = E_{b_t}[success | do(a)] − E_{b_t}[success | do(a_task)] − λ_r·risk(a) − λ_t·Δt(a)`，其中 `a_task` 为同一状态下策略的纯推进动作。

**定义 U18（风险预算）** `ρ_{t+1} = ρ_t − risk(a_t)`；仅当 `risk(a) ≤ ρ_t` 且 `n_probe < N_probe^max` 时允许探测。

**定义 U19（会话）** `S_i = (port_i, h_i, b^i, ρ_i, n_probe^i)`；`reset(port_i)` 仅重置 `S_i`，不得触碰 `S_j (j≠i)`。

**定义 U20（批处理调度）** 在窗口 `w` 内到达的请求集合 `B_t`，批服务时间 `s(B_t)`；`p99` 延迟由批服务排队模型给出上界。

**定义 U21（场景整形算子）** `s = (pre, post, op, risk)`，`op` 为非抓取原语；仅当 `pre` 满足、`post` 不破坏目标可达性、且 `E[Δsuccess] > E[damage] + cost` 时执行。

**定义 U22（可信度分数）** `T = f(σ_lat, jerk, probe_rate, task_usefulness)`；约束 `T ≥ T_min`、`probe_rate ≤ r_max`、`jerk ≤ J_max`。

**定义 U23（退化格）** `D0 ≺ D1 ≺ D2 ≺ D3 ≺ D4`，级别越高越接近第 1 轮基线；`D4 = passthrough`。

**定义 U24（审计证书）** `C = (probe_log, VOI_estimates, risk_classes, latency_stats, jerk_stats, degradation_events)`，可导出、可回放。

def choose(cands, b, budget, trust):
    best, best_voi = None, -inf
    for a in cands:
        if not trust.allows(a):
            continue
        if a.risk_class == "irrev" and a.risk > budget.left:
            continue
        if a.kind == "probe" and budget.n_probe >= N_PROBE_MAX:
            continue

        p_base = value_model(b, a.task_equiv)      # 同状态纯推进动作
        voi = p_succ - p_base - LAM_R * a.risk - LAM_T * a.dt
        if voi > best_voi:
            best, best_voi = a, voi
    return (best if best_voi > 0 else task_action(cands)), best.kind

## 5. 推导（引理 L8–L14）

**引理 L8（信息补贴）** 若计分只依赖终态成功、时间无独立惩罚，且探测的风险被预算 `ρ` 约束，则任一满足 `VOI(a) > 0` 的探测都不降低期望得分；最优探测率满足"边际 VOI = 边际风险"。*证明要点*：得分 `S = 1[success]`，`E[S] = P(success)`；探测只通过改变后验与状态影响 `P(success)`，时间项系数为 0，风险项被 `ρ` 约束；对候选动作取 argmax 即得。∎

**引理 L9（契约可辨识性）** 若探测集 `A_probe` 对决策等价类**可分离**（对任意 `θ_1 ≁_D θ_2`，存在 `a` 使 `P(o,Δt | θ_1, a) ≠ P(o,Δt | θ_2, a)`），则贝叶斯信念 `b_t` 在重复探测下依概率收敛到某个 `~_D` 等价类；有限样本下错误率随探测数指数下降（Chernoff 界）。∎

**引理 L10（探测安全性）** 若每个探测 `a` 满足：①幅度与时长有界；②存在恢复动作 `rec(a)`；③不可逆风险 `risk(a) ≤ ρ_t`，则单 episode 内由探测导致的不可逆损坏概率 ≤ `1 − ∏_t (1 − risk(a_t)) ≤ Σ_t risk(a_t) ≤ ρ_0`；配合最大次数 `N_probe^max`，风险有界。∎

**引理 L11（批处理延迟上界）** 在窗口 `w`、批服务时间 `s(B)`、到达率 `λ` 下，单请求延迟 `L ≤ w + s(B) + Q/μ`；当 `λ·E[s] < 1` 时队列稳定，p99 可由 M/G/1 近似给出；精度相位绕过批处理时 `L ≤ s_single`。∎

**引理 L12（退化单调性）** 若退化级别 `D_k` 只移除可选组件并最终回退到第 1 轮基线，则 `E[success | D_k] ≥ E[success | D_{k+1}] − ε_k`，且不引入基线之外的新失败模式；`D4 = passthrough` 保证最小可提交。∎

**引理 L13（可信度保持）** 若探测满足速率 `≤ r_max`、jerk `≤ J_max`、且动作来自与任务动作相同的分布，则可信度分数 `T` 保持在基线置信区间内；若 `T < T_min`，TrustShield 关闭探测，故不会因探测本身触发 irregular 判定。∎

**引理 L14（整形单调性）** 场景整形仅在 `E[Δsuccess] > E[damage] + cost` 且 `post` 保持目标可达时执行；否则为 no-op。因此在该模型下整形不会降低期望成功。∎

## 9. 风险登记册与剪枝预案

| 风险 | 概率 | 影响 | 对冲 |
|---|---|---|---|
| **探测造成不可逆损伤**（碰倒 / 卡死 / 推远目标） | 中高 | 高 | 风险预算 + 恢复动作 + 幅度/时长上限 + 最大次数 + 默认禁不可逆探测 |
| **探测被判定 irregular** | 中 | 高（可信度） | TrustShield：速率 / 平滑 / 任务有用性约束 + 审计证书 |
| **契约辨识错误** | 中 | 中高 | 只辨识决策等价类 + 保守回退 D0 + 真机后验校准 |
| **批处理抬高延迟** | 中 | 中 | 精度相位优先 + 自适应窗口 + 过载降级 |
| **场景整形违反任务语义** | 中 | 高 | 先问规则；只动明确遮挡的非目标物；默认关闭 |
| **ReplayTwin 与真机不一致** | 中高 | 中高 | 预注册 <0.8 剪枝；最终以真机 A/B 为准 |
| **合规**（多专家 / 在线更新 / 整形） | 中 | 高 | 书面确认；单专家降级形态；黑名单 |
| **端口 / token / 并发工程事故** | 中 | 高（直接失败） | 自动化体检 + 8 h 压测 + passthrough |

**剪枝预案（下一轮起执行）**：
- **必保**：IP-09（契约信息价值最高）、IP-10（test-lift 子集）、IP-11（工程底座）、IP-14（离线迭代能力）。
- **优先深化**：IP-15（收益最直接）、IP-13（可信度是相对优势）。
- **条件推进**：IP-12（依赖规则确认）、IP-09 的 interpolation probe（依赖安全评估）。
- **暂存**：其余高风险探测。
