# 第 2 轮 · YIELD：把人为干扰变成“让位-推断-恢复”的测试时算力窗口

> 检索/复核日期：2026-10-25（UTC）。赛事身份确认：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API。本轮灵感词是「智能体」「深度学习」「共情表达」。

**主判断：第 7 轮 PILOT 把“终局放置”认定为成功率闸门和步骤分大头，这条继续成立；本轮加一条与它正交、且被官方规则精确量化的杠杆——每个任务 10 次评测里有 2 次是人为干扰（64/320 试次，20%），而官方 `generalization` 字段为每个任务给出了两条人为干扰备注（`human_1_note` / `human_4_note`），很可能就是两次 human 评测的剧本（待 W1 确认）。当前 VLA 把它们当随机扰动；我们要把它们当“可推断的意图信号”。做法不是再加一个 LLM 规划器，而是单模型智能体运行时：检测到人插手 → 让位（yield）→ 用这段安全的停顿跑潜空间世界模型 → 推断干预意图 → 在 resume / rollback / restore / alternative / abort 里选恢复 → 验证后继续。核心洞见：让位既是社会性的正确行为，也是测试时算力的天然预算窗口（“Yield-to-Think”）。**

上一轮（PILOT，第 7 轮）的教训是：不要把部署工程当研究主轴；本轮的“智能体”很容易滑回“LLM 规划器 + VLA”的双模型堆栈，而赛制明确要求“同一模型、不得混合多个模型”，且官方会记录延迟与动作统计规律。因此本轮的关键设计约束是：**Agent-as-Runtime, not Agent-as-Model**——一个 checkpoint + 若干轻量头 + 确定性运行时；不是第二个大模型。

## 0. 本轮先核实：八个事实

### 0.1 规则读到了关键部分：10 次/任务、5 类×2、180s、单模型

官方参赛手册（中/英，文档 Modified Aug 07；[S1][S2]）明确：

- 32 个任务，每个任务独立跑 **10 次**；10 次中包含 **5 种泛化类型，每种各 2 次**：位置、干扰物、桌面背景、未见物品、人为干扰。
- 每个任务单次真机执行 **最大 180 秒**，超时记失败，并按执行情况计算步骤分。
- 只设 **通才模型赛道**：必须一个模型完成全部 32 个任务；“不得混合使用多个模型一起进行测试”；模型类型不限（World Model、VLA 均可）。
- 排名：先按 32 个任务的**总平均成功率**；相同则按**总平均步骤分**；再相同则**提交日期更早**者靠前。
- 另有**不计分的单任务调试通道**（只测 1 个任务，不进榜）。

这回答了几个跨轮开放问题：人为干扰不是“某几个任务的特例”，而是**每个任务固定 2/10**；总试次 320，其中人为干扰 **64 次**。4.2 的具体得分公式与 4.3 的入围条件仍未完整读到（飞书文档 2.3 之后未渲染），标“未核实”。

### 0.2 榜单仍是占位，29.7% 不是实测

`leaderboard.html` 显示 8 个模型，榜首 MolmoAct/DexHacker 为 **29.7% / 39.0**；但 `leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，8 模型 × 32 任务 = 256 条 `task_metrics`，`runs.html` 是 256/256，详情页每段视频都写“测试视频占位，后续可替换为真实视频文件”（[S4][S5][S6]）。JSON 的发布时间是 **2026-10-08**，此后没有更新。

所以：**“榜首不到 30%”目前只能当“预期上限/难度先验”，不能当真实基线，更不能用来推断哪种方法更强。** 但它与公开的 OOD 桌面操作结果方向一致——空间/物体泛化通常显著低于名义分布，所以可以谨慎地把它当作“真实榜首大概率也不高”的弱先验，而不是精确基线。

### 0.3 数据没变：32×约 1k、33k、169h、四路相机、30fps

HF collection 仍是 32 个数据集，每个 970–1,530 条，合计约 33k / 169h；HangCup 1,043 条、194,564 帧、30fps、`head_stereo_left/right` + `wrist_left/right` 四路 480×640（H×W，AV1 编码）；数据集 `lastModified` 为 **2026-10-14**（[S9][S10]）。数据是**名义演示**，没有人为干扰、没有失败恢复、没有 5 类泛化的逐帧标签——这正是本轮要补的缺口。

### 0.4 提交接口 v2 未变，但多了两条“可信度”约束

`unibot_submission` 仍是 2026-08-21 的 v2（[S11][S12]）：

- 观测四路 RGB + 双臂关节/EE 位姿 + 夹爪 + 下半身 + `observation.language` 单字符串；`obs_delta_indices` 决定传哪些键、每键堆叠几帧；`image_resize`、`action_chunk_size` 自定；动作空间 joint / ee 互斥。
- 评测跨 **N 台机器人**，需要从 8765 起暴露 **N 个连续端口**，每端口独立完成一条 episode，状态必须隔离。
- README §6 明确：评测会记录每一步的**延迟及其波动**、返回动作的**统计规律**，并可能随结果展示；建议保持延迟稳定、动作良构、避免异常模式。

这条对“智能体”方案很关键：一个开放式 LLM 规划循环（延迟忽高忽低、动作由 planner 直接给）会踩“可信度”红线。我们的运行时必须是**有界延迟、类型化状态转移、动作仍由 VLA 生成**。

### 0.5 官方模型栈：WLA-1.0 是现实底座，但没有公布逐任务成功率

- **UnifoLM-WLA-1.0**：6B，约 2,500 小时真机数据、64 个任务，Apache-2.0，24GB 可微调；2026-09-28 放出 Base 与微调代码（[S13]）。
- **UnifoLM-WMA-0**：World-Model-Action，世界模型可作交互式模拟器或策略增强头（[S14]），但发布于 2025-09，数据和任务覆盖都早于本届 33k。
- **UnifoLM-VLA-0**：2026-01 的 VLA 版本（[S15]）。

注意：WLA-1.0 官方**没有公布逐任务成功率**，第三方也指出“没有 per-task success rate / failure counts”（[S17]）。所以不能假设“用 WLA 就自动领先”；它只是一个合规、可微调、与 G1/Dex1 同源的起点。WMA-0 也不应直接替代 WLA；更合理的是在 WLA 上加一个轻量潜空间世界模型头。

### 0.6 2026 年的强证据：运行时 + 世界模型 + 意图推断

本轮读到的 2026 论文给出一个高度一致的模式：**冻结/近冻结的策略 + 测试时脚手架/恢复 + 潜空间预判**，往往比重新训练一个大 VLA 更划算。

- **Harness VLA**（[P1]）：冻结 VLA 作为“可重试的接触丰富原语”，外面套 memory / validators / execution loop / failure models；LIBERO-Pro +38.6pp、RoboCasa365 +25.4pp、RoboTwin C2R 58.4%。
- **SERA**（[P2]）：VLM planner + 固定 VLA executor + 可编辑 harness；RoboMME 51.38% vs 44.38%（无自演化）。
- **Recova**（[P8]）：agent 在数字孪生里诊断失败、生成恢复程序，真机 DAgger 23.8%→77.5%→87.5%；四轮采集后人为干预从 87.5% 降到 0%。
- **VLA-Corrector**（[P7]）：潜空间视觉监控器检测“动作块过期”，触发截断与校正重规划；MetaWorld +15.65pp、真机 +17.7pp；演示里就是“人移动抽屉/碗，机器人恢复”。
- **FaultEval**（[P10]）：VLM 诊断 + 回滚 + 定向恢复；LIBERO +13%、真机 +35%。
- **Causeway**（[P11]）：指令切换后“任务孤岛”，训练免费的推理期干预把成功率从 3–26% 提到 47–65%。
- **AHEAD**（[P3]）：4.9M 参数的潜空间世界模型 + 冻结 7B OpenVLA，20 个动态场景 79–97%，最强基线 31–58%。
- **VeriVLA**（[P4]）：JEPA 潜空间世界模型做测试时验证，真实任务完成分 50.8%→65.5%，每次触发 +326ms；RoboTwin 随机化 62.8%→69.6%。
- **VLA-ATTC**（[P5]）：相对动作 critic 做自适应测试时算力，PI0.5 失败率降一半以上，真机 +17.3%。
- **Kintsugi-VLA**（[P9]）：把失败 rollout 变成恢复数据，恢复成功率 +5.8/6.7pp。
- **HINT**（[P12]）：只在“操作模式切换点”调用语义推理，再用多视角 grounding/跟踪维持意图；强调“意图是中间表示”。
- **Correction Timing**（[P13]，AAMAS 2026）：人决定“何时介入”的时机与初始方向，能更快推断其纠正目标。

这些证据合起来支持一个判断：**在 UniBot 这种 32 任务、单模型、远程 API、180s 的赛制里，最划算的边际改进很可能不是“再训一个更大的端到端 VLA”，而是“给现有 VLA 加一个会预判、会验证、会恢复的运行时”。**

### 0.7 人为干扰轴是“可枚举的 64 个脚本”，不是开放世界

每个任务的 `info.json` 的 `generalization` 字段给出 `human_1_note` 与 `human_4_note`（[S8]）。它们很可能是两次 human 评测的剧本，但命名/对应关系需 W1 向官方确认。本轮复核了三个高价值任务：

- **T27 StackBowls**：`human_1` =「把粉色碗向下移动」；`human_4` =「叠了第二个之后拿下第二个」。
- **T19 ZipUp**：`human_1` =「把包向左边移动」；`human_4` =「拉上拉链之后拉开」。
- **T10 PlugCharger**：`human_1` =「抓插头前进行移动」；`human_4` =「将插头拔起」。

加上上一轮整理的其余任务，共 **32×2 = 64 条官方备注**（暂按“脚本”使用，待确认对应关系）。从已复核的 6 条看，多数是“对某个对象做一次 1-DOF 平移”或“在某一步完成后撤销它”；全量 64 条待 W1 核对。这意味着：

1. 评测的人为干扰**不是任意开放世界**，而是一个**每任务 2 类的闭集**（外加可能的未知扰动）。
2. 我们不需要训练一个通用的“人类意图理解大模型”；只需要一个**每任务 2–3 类的分类器 + 一个未知类兜底**。
3. 官方备注是**免费的先验/标签**：可以直接构造训练数据、构造恢复对、构造测试场景。

这是本轮最锋利的发现：**别人看到的是“2/10 的随机扰动”，我们看到的是“64 个已知剧本的闭集考试”。**

### 0.8 单模型合规边界：一个 checkpoint + 多个头，不是 LLM+VLA

规则说“所有任务须基于同一模型完成，不得混合使用多个模型一起进行测试”，英文是“mixing multiple models for different tasks is not permitted”。严格解释可能禁止“planner 一个模型 + executor 一个模型”的堆栈；宽松解释只禁止“按任务换模型”。我们不能赌宽松解释，因此：

- **唯一学习模型**：一个 WLA-1.0 checkpoint（可加 LoRA/action expert）。
- **轻量头**：HIM（干预意图）、IA-WM（潜空间世界模型）、RRC（相对恢复 critic）都挂在这个 checkpoint 的视觉/语言特征上，作为同一模型的头；不是独立部署的第二个模型。
- **确定性运行时**：SSG 状态机、让位/恢复逻辑、谓词校验、预算守卫都是代码，不是模型。
- **Tier A 兜底**：如果组委会认定“多个头也算多模型”，退化为纯确定性版本（官方脚本先验 + 运动检测 + 回滚/恢复原语），仍然能吃到一部分收益。
- 在模型卡中完整披露；通过官方手册第六章的联系方式发邮件确认边界。

## 1. 三个词，各自钉到事实上

### 1.1 智能体：2026 年的增益主要来自“运行时”，不是更大的 VLA

把 0.6 的证据按“增益来源”拆开：

| 工作 | 改了什么 | 增益 | 对我们的含义 |
|---|---|---|---|
| Harness VLA | 冻结 VLA + memory/validators/loop | +38.6 / +25.4pp | 运行时可以独立于权重产生大增益 |
| SERA | VLM planner + 可编辑 harness | +7.0pp | 历史依赖任务需要显式上下文 |
| Recova | 失败诊断 + 恢复程序 + 真机 DAgger | 23.8→87.5% | 恢复能力可以“长”出来 |
| VLA-Corrector | 潜空间监控 + 截断 + 校正 | +15.65 / +17.7pp | 动作块过期是真实失败模式 |
| FaultEval | 诊断 + 回滚 + 恢复 | +13 / +35pp | 回滚是有效的恢复原语 |
| Causeway | 训练免费的推理期干预 | 3–26→47–65% | 状态可及性可以被“写回” |
| Cracking Mobile Manipulation | 失败引导的 agentic intervention | 19→47→49% | 组合技能需要运行时补位 |

但 UniBot 有两个别人没有的约束：

1. **单模型**：不能把 GPT/Claude 当 planner 再配一个 VLA。
2. **可信度**：官方记录延迟波动与动作统计规律；开放式 agent 的“想一想再动”会造成延迟尖峰和动作不连续。

因此我们的“智能体”定义是：

> **一个确定性的、有界延迟的运行时，把 VLA 当作可重试的接触丰富原语；所有语义判断来自同一个 checkpoint 的头，所有状态转移都是类型化的，所有动作仍由 VLA 生成。**

这既拿到 Harness VLA 类工作的增益，又不引入第二个模型、不破坏延迟/动作的统计规律。我们把它叫 **Agent-as-Runtime**。

### 1.2 深度学习：世界模型做“潜空间验证器”，不做像素生成器

“深度学习”最容易被误解成“再训一个大模型”。本轮的证据指向另一种用法：

- **AHEAD**：4.9M 参数的潜空间世界模型，挂在冻结 7B VLA 上，预测未来 patch token；动态场景 79–97%，基线 31–58%。
- **VeriVLA**：JEPA 潜空间世界模型对候选动作块排序；真实任务 50.8→65.5%，每次触发仅 +326ms；不生成像素。
- **VLA-ATTC**：相对动作 critic 做 pairwise 比较，避免不稳定的绝对值估计；PI0.5 失败率降一半。
- **VLA-FAIL**：不需要失败数据，用 last-layer Mahalanobis + action consistency 做早期失败检测。
- **Kintsugi-VLA**：用仿真“干预可恢复性”筛选失败状态，生成恢复数据；恢复成功率 +5.8/6.7pp。

映射到 UniBot：

1. **IA-WM（Intervention-Aware World Model）**：在 WLA 的视觉 token 空间里预测“人干预后 0.5–2s 的潜状态 + 任务进度”，条件是人手/物体的短时运动。它不生成视频，只输出 latent 和 progress，用于给 K 个恢复候选打分。
2. **RRC（Relative Recovery Critic）**：对同一状态下的 K 个候选恢复做 pairwise 排序，训练信号来自“哪个恢复最终完成了任务/恢复了步骤谓词”。这比绝对价值回归稳。
3. **ITC（Intervention Token Conditioning）**：把 HIM 输出的结构化干预描述（类型/目标/步骤/意图）作为额外 token 拼进语言上下文，微调同一个 VLA 生成恢复动作。这样“恢复”不是外挂 planner，而是模型自己的条件生成。
4. **不做**：像素级视频生成、每 episode 梯度更新、独立部署的第二个世界模型。前者太慢，中者违反延迟/可信度，后者违反单模型边界。

### 1.3 共情表达：认知共情有分，情绪表达没分

把“共情”拆成三层，逐层对照赛制：

| 层 | 定义 | UniBot 里的评分相关性 | 结论 |
|---|---|---|---|
| 认知共情 | 从人的干预中推断其目标/意图（为什么移这个物体？想恢复还是想阻止？） | **高**：直接决定 rollback/restore/alternative 的选择 | 主攻 |
| 行为共情 | 让位、避碰、恢复、用动作表达“我理解了你” | **中**：让位避免碰撞、节省时间；表达对脚本化评测者影响有限 | 保留“让位”，弱化“表达” |
| 情绪共情 | 识别/表达情绪（安抚、表情、语气） | **低/无**：评测者按剧本干预，不因机器人表情改变行为；没有情感评分 | 砍掉 |

文献支撑“认知共情”这一层是可行的：

- **Correction Timing**（[P13]）：人“何时介入”与“初始方向”能快速推断纠正目标；说明干预动作本身携带意图信息。
- **HINT**（[P12]）：把“意图”作为稀疏切换的中间表示，只在模式转换点做语义推理，其余时间靠视觉跟踪维持；这正好对应“人干预前/后”的模式转换。
- **GazeVLA / EDITH**（[P15][P16]）： gaze/非语言信号可以作为意图的中间表示；我们没有 gaze 输入，但人手/物体运动是弱化版。
- **GUIDER**（[P14]）：双阶段概率意图估计；说明“意图”可以做成可更新的 belief，而不是一次性分类。
- **Recova**（[P8]）：把“人为干预率”作为系统级指标，四轮后降到 0；说明“减少人插手”本身是一个可优化的目标。

所以本轮对“共情表达”的裁剪是明确的：

> **保留“认知共情”（干预意图推断）和“行为共情”的最小核心（安全让位/恢复）；不做情绪识别、不做表情/语气、不做社交机器人。** “表达”只在“让位时头/ gaze 朝向人、慢速后退”这种**可被评分间接奖励**的范围内保留（减少碰撞、减少无效动作），不额外投资。

## 2. 算术：人为干扰是“被低估的 20%”

### 2.1 上界与下界

设人为干扰试次的基线成功率为 `p_h`，YIELD 把它提到 `p_h+Δ_h`。其余 256 个试次不变，则总成功率增益：

`Δ_overall = 0.2 × Δ_h`

- `p_h=20%`，YIELD 到 60%：`Δ_h=40pp` → **+8pp overall**
- `p_h=40%`，YIELD 到 70%：`Δ_h=30pp` → **+6pp overall**
- `p_h=70%`，YIELD 到 80%：`Δ_h=10pp` → **+2pp overall**（不值得重投）

我们不知道 `p_h`。但有两个理由相信它**低于名义成功率**：

1. 33k 演示全是名义轨迹，没有人干预；模型没有见过“人手把物体拿走/撤销步骤”。
2. 现有 VLA 的动作块是开环执行的；人一干预，队列里的动作就过期（VLA-Corrector 的“stale chunk”问题），而模型没有显式的“中断-重规划”机制。

因此 `p_h` 很可能在 10–40% 区间；`Δ_h` 的合理目标是 +30–50pp，对应 overall **+6–10pp**。这与 PILOT 的“终局放置 +15pp × q(0.5–0.7) = +7–10pp”是同一量级，而且是**正交**的：两者可以叠加。

### 2.2 步骤分：比成功率更划算

人为干扰试次的失败往往不是“全错”，而是“做到第 2 步被撤销，后面全丢”。如果 YIELD 能 rollback/restore 并继续，步骤分可以从“前 1–2 步的部分分”恢复到“接近满分”。假设 64 个干扰试次的平均步骤分从 30 提到 60（`Δ_s=30`），总步骤分增益：

`0.2 × 30 = +6 分`

而排名在成功率相同时按步骤分排序，所以这 6 分在拥挤的中游可能直接决定名次。

### 2.3 与放置杠杆的关系

| 杠杆 | 作用范围 | 成功率增益近似 | 步骤分增益近似 | 是否共享恢复回路 |
|---|---|---|---|---|
| 终局放置 +15pp | 全部 320 试次 | +15×q ≈ +7–10pp | +0.398×15 ≈ +6 分 | 是（SVL） |
| 人为干扰 +30–50pp | 64 试次 | +6–10pp | +6 分 | 是（YTE/SVL） |
| 两者叠加 | — | +13–20pp | +12 分 | 同一套“验证-恢复” |

关键：**它们不是两个独立的工程项目，而是同一个“状态机 + 验证 + 恢复”运行时的两个应用场景。** 放置失败是“机器人自己造成的失败”，人为干扰是“外部造成的失败”；恢复原语（rollback、regrasp、restore、retry）高度复用。这是本轮把 YIELD 叠在 PILOT 上、而不是另起炉灶的理由。

### 2.4 统计功效：64 个干扰试次能测出什么？

- 64 个干扰试次，基线 `p_h=0.3`，若观察到 +30pp，非配对标准误约 `sqrt(2×0.3×0.7/64)=8.1pp`；+30pp 约 3.7 SE，可检测。
- 320 个总试次，+6pp 的整体效应，标准误约 `sqrt(2×0.3×0.7/320)=3.6pp`；+6pp 只有 1.7 SE，**不足以单独宣称显著**。
- 因此：**不要把 320 试次的全量榜当唯一证据**。用离线重放（64 脚本 × 多次）和单任务调试槽做“机制验证”，用全量榜做“方向验证”；预注册主要终点（human-trial success、step score、time-to-recovery），不要事后挑指标。
- 单任务调试槽每个任务只有 10 次，其中 2 次人为干扰；单任务上测 +30pp 的噪声极大。调试槽应用来看**失败模式/延迟/恢复是否触发**，不是用来做显著性检验。

### 2.5 时间预算

- 名义 episode 中位数约 6–10s（HangCup 中位 177 帧 ≈ 5.9s；长程任务更长）。
- 每次干预：让位 0.3–0.8s + 推断/排序 0.3–0.8s + 恢复 1–3s ≈ 2–4.5s。
- 每个任务最多 2 次人为干扰；即使都触发，额外 4–9s，远小于 180s。
- 长程任务（T16/T17/T31）可能已用 60–120s；仍可承受，但设“最多 3 次恢复、总恢复时间 ≤20s”的守卫。

### 3.2 “Yield-to-Think” 循环（伪代码）

```python
def step(obs, runtime):
    # 1. 正常执行
    if not runtime.intervention_detected(obs):
        chunk = runtime.policy.act(obs, runtime.ssg.current_step)
        return chunk

    # 2. 让位：安全第一，同时把“停顿”变成算力预算
    runtime.yield_to_human(obs)          # freeze arms, retreat, gaze
    if not runtime.human_left_workspace(obs, dwell=0.5):
        return runtime.hold()             # 继续等，不抢

    # 3. 推断：闭集先验 + 学习残差
    intent = runtime.him(obs)            # type, target, step, direction
    runtime.ssg.apply_intervention(intent)  # undo -> rollback; remove -> alternative

    # 4. 预判：潜空间 rollout + 相对排序
    candidates = runtime.propose_recoveries(intent)   # resume/rollback/restore/alternative
    scores = runtime.ia_wm.rank(obs, candidates)      # progress, collision, uncertainty
    best = runtime.rrc.select(candidates, scores)

    # 5. 条件生成 + 验证
    token = runtime.itc.encode(intent, best)
    for attempt in range(2):
        for chunk in runtime.policy.act(obs, token):
            send(chunk)
            if runtime.ssg.predicate_met(obs):
                break
        if runtime.ssg.predicate_met(obs) and runtime.stable(obs, 0.5):
            runtime.ssg.resume()
            return runtime.hold()
        runtime.repair_or_regrasp(best)
    return runtime.safe_abort()
```

### 3.3 五种恢复模式

| 模式 | 触发 | 动作 | 例子 |
|---|---|---|---|
| resume | 人只是短暂遮挡/轻推，目标状态未变 | 等手离开后继续当前步骤 | T10 人手经过插头 |
| rollback | 人撤销了已完成步骤（undo） | 把 SSG 回退到该步，重做 | T27 叠了第二个又拿走；T19 拉上又拉开 |
| restore | 人把目标物体移走/移偏 | 先把物体放回可用位姿，再继续 | T02 水果被推走；T13 试管被移动 |
| alternative | 人拿走了目标物体/占用了槽位 | 换一个同类物体/槽位，或调整顺序 | T11 电池被拿走；T24 传送带物品被放回起点 |
| abort | 任务已不可完成/安全风险 | 安全停住，保留步骤分 | 人把整个容器拿走 |

这五种模式是**类型化的**，不是 LLM 自由生成；这保证延迟和动作可预测，也方便做模型卡/合规说明。

### 3.4 Tier A / Tier B：先合规，再学习

**Tier A（确定性，1–2 周可跑）**
- HIM 用“官方脚本先验 + 简单运动检测”：对每个任务，只有 2 个已知干预脚本；用物体位移方向/人手进入区域匹配。
- 恢复用确定性原语：回到记录的 pre-intervention EE pose、重抓、放回、重做当前步。
- 不需要新模型；完全符合最严格的“单模型”解释。
- 预期能吃到“已知脚本”的大部分收益；对未知扰动退化。

**Tier B（学习头，4–8 周）**
- HIM：在 WLA 视觉特征上加分类头（2–3 类 + unknown），用合成干预 + 少量真机数据训练。
- IA-WM：潜空间世界模型头，预测 post-intervention latent/progress；只在触发时 rollout K 个候选。
- RRC：pairwise 恢复排序头。
- ITC：把干预 token 拼进语言上下文，LoRA 微调同一 VLA。
- 全部挂在同一个 checkpoint 上；运行时仍是确定性代码。

这个分层是风险控制的核心：**Tier A 保底，Tier B 冲上限；即使单模型审计不通过，Tier A 仍然可提交。**

## 0. 摘要

**问题**：32 个任务、每个 10 次评测，其中 5 类泛化各 2 次；人为干扰占 **64/320 = 20%**。现有 VLA 在名义数据上训练，遇到人插手时动作块过期、目标状态被改变，往往直接失败；而官方 `info.json` 为每个任务给出了 2 条人为干扰备注（`human_1_note` / `human_4_note`），很可能对应两次 human 评测（待 W1 确认），这使“人为干扰”至少成为一个**有强先验的闭集问题**，而不是开放世界。

**判断**：最划算的边际改进不是再训一个更大的端到端 VLA，而是给现有 VLA 加一个**单模型、确定性、有界延迟的智能体运行时**：检测干预 → 让位 → 用停顿跑潜空间世界模型 → 推断干预意图 → 选择恢复 → 验证后继续。我们把它称为 **YIELD / Yield-to-Think**。

**算术**：若人为干扰试次基线成功率 `p_h=0.2–0.4`，YIELD 提升 `Δ_h=30–50pp`，则总成功率 +6–10pp；若同时恢复步骤分 `Δ_s=30`，总步骤分 +6 分。它与 PILOT 的“终局放置 +15pp”正交，且共享同一套“验证-恢复”回路。

**证据**：2026 年的 Harness VLA（+38.6 LIBERO-Pro / +25.4 RoboCasa365）、SERA（+7.0 RoboMME）、Recova（真机 23.8→87.5%）、VLA-Corrector（+15.65 MetaWorld / +17.7 真机）、AHEAD（4.9M 参数世界模型 79–97% vs 31–58%）、VeriVLA（真实 50.8→65.5%，+326ms）、VLA-ATTC（失败率减半）共同支持“运行时 + 潜空间预判 + 恢复”的路线。

**合规**：一个 WLA-1.0 checkpoint + 同源轻量头（HIM / IA-WM / RRC / ITC）+ 确定性代码；不引入第二个 LLM；Tier A 纯确定性兜底，Tier B 学习头冲上限；模型卡披露并向官方确认“单模型”边界。

**一句话**：把 64 个人为干扰试次当成“64 个已知剧本的闭集考试”，用 Yield-to-Think 运行时先吃下这 20%，再把同一恢复回路复用到终局放置失败。

## 2. 评分算术与统计功效

### 2.1 人为干扰轴的上界

设 64 个干扰试次的基线成功率为 `p_h`，YIELD 后为 `p_h+Δ_h`；其余 256 次不变。总成功率：

`S_overall = (256 × p_n + 64 × (p_h+Δ_h)) / 320`

增益：

`ΔS_overall = 0.2 × Δ_h`

| 场景 | p_h | p_h+Δ_h | Δ_h | 总成功率增益 |
|---|---|---|---|---|
| 悲观 | 0.10 | 0.40 | +30pp | +6.0pp |
| 中性 | 0.25 | 0.60 | +35pp | +7.0pp |
| 乐观 | 0.40 | 0.80 | +40pp | +8.0pp |
| 上限 | 0.50 | 0.95 | +45pp | +9.0pp |
| 无效 | 0.70 | 0.80 | +10pp | +2.0pp |

**判据**：若赛前估计 `p_h>0.7`，YIELD 的上限只有 +2pp，不值得重投；若 `p_h<0.4`，+6–9pp 值得作为主攻之一。

### 2.2 步骤分

人为干扰导致的失败往往保留部分步骤分。设 64 次干扰试次的平均步骤分从 `s_h` 提到 `s_h+Δ_s`，总步骤分增益为 `0.2Δ_s`。

| Δ_s | 总步骤分增益 |
|---|---|
| 20 | +4 分 |
| 30 | +6 分 |
| 50 | +10 分 |

排名在成功率相同时看步骤分，因此 +6 分在拥挤的中游可能直接决定名次。

### 2.3 与 PILOT 放置杠杆的叠加

| 杠杆 | 覆盖试次 | 成功率增益 | 步骤分增益 | 共享组件 |
|---|---|---|---|---|
| 终局放置 +15pp | 320（全部） | +15×q，q≈0.5–0.7 → +7.5–10.5pp | +0.398×15 ≈ +6 分 | SSG+/SVL+ |
| 人为干扰 +30–50pp | 64（20%） | +6–10pp | +6 分 | YTE/HIM/IA-WM/RRC/ITC |
| 叠加 | — | **+13–20pp** | **+12 分** | 同一“验证-恢复”运行时 |

注意：两个杠杆不是线性独立（放置失败也会触发恢复），叠加值是上界估计；实际应按消融测量。

## 3. 架构

### 3.1 设计原则

1. **一个 checkpoint**：WLA-1.0（可加 LoRA/action expert）；所有学习组件挂在同一 checkpoint 的特征上，不部署第二个模型。
2. **运行时是代码**：状态机、谓词、预算、让位/恢复逻辑都是确定性 Python，不是 LLM 自由生成。
3. **有界延迟**：每次 deliberation 有硬预算（HIM+IA-WM+RRC ≤0.8s）；单次干预决策路径 p99 ≤1.0s；超预算直接走 Tier A。
4. **动作由 VLA 生成**：planner/头只输出“选哪个恢复/哪个 token”，不直接输出电机动作；保证动作连续、可审计。
5. **安全优先**：检测到人就冻结/后退；人手离开工作区 ≥0.5s 才恢复；任何异常 abort 保步骤分。
6. **可回退**：Tier A（纯确定性）永远可用；Tier B 任一头失败都可以单独关闭。

### 3.4 运行时状态机

| 状态 | 进入条件 | 允许动作 | 退出条件 |
|---|---|---|---|
| `NOMINAL` | 无干预 | 执行当前步骤 | 检测到干预/步骤完成/失败 |
| `YIELD` | 人进入工作区或物体被人手接触 | 冻结、后退、头/ gaze 朝向人 | 人手离开 ≥0.5s |
| `INFER` | 人手离开 | HIM 分类 + SSG+ 更新 | 意图置信度 ≥阈值或超时 |
| `DELIBERATE` | 意图已知 | IA-WM rollout + RRC 排序 | 选出候选或超预算 |
| `RECOVER` | 候选已选 | ITC 条件生成 + 执行恢复原语 | 谓词满足/重试耗尽 |
| `VERIFY` | 恢复动作结束 | SVL+ 稳定性/谓词检查 | 通过→NOMINAL；失败→RECOVER/ABORT |
| `ABORT` | 不可恢复/安全风险/超时 | 安全停住、释放、记录 | episode 结束 |

### 3.5 伪代码（运行时主循环）

```python
class YieldRuntime:
    def __init__(self, policy, him, ia_wm, rrc, itc, ssg, hisl):
        self.policy, self.him, self.ia_wm = policy, him, ia_wm
        self.rrc, self.itc, self.ssg, self.hisl = rrc, itc, ssg, hisl
        self.recovery_budget_s = 20.0
        self.max_triggers = 3

    def act(self, obs):
        if self.ssg.done(obs):
            return self.policy.stop()

        if not self.detect_intervention(obs):
            return self.policy.act(obs, self.ssg.current_prompt())

        # 1) 让位：安全 + 把停顿变成算力窗口
        self.yield_to_human(obs)
        if not self.human_left(obs, dwell=0.5):
            return self.hold()

        # 2) 推断：闭集先验 + 学习残差
        intent = self.him.predict(obs, prior=self.hisl.prior(self.ssg.task, self.ssg.step))
        self.ssg.apply(intent)

        # 3) 预判：潜空间 rollout + pairwise 排序
        candidates = self.propose(intent)          # resume/rollback/restore/alternative
        feats = self.ia_wm.rollout(obs, candidates) # latent, progress, collision, uncertainty
        best = self.rrc.select(candidates, feats)

        # 4) 条件生成 + 验证
        prompt = self.itc.encode(intent, best, self.ssg.current_prompt())
        for attempt in range(2):
            for chunk in self.policy.act(obs, prompt):
                self.send(chunk)
                if self.ssg.predicate_met(obs):
                    break
            if self.ssg.predicate_met(obs) and self.stable(obs, 0.5):
                self.ssg.resume()
                return self.hold()
            self.repair(best)
        return self.safe_abort()
```

### 3.6 五种恢复模式

| 模式 | 触发 | 原语 | 例子 | 预期收益 |
|---|---|---|---|---|
| `resume` | 人只是短暂遮挡/轻推，目标状态未变 | 等手离开，继续当前 chunk/步骤 | T10 人手经过插头 | 避免无谓回滚 |
| `rollback` | 人撤销了已完成步骤 | SSG+ 回退到该步，重做 | T27 叠了第二个又拿走；T19 拉上又拉开 | 恢复大部分步骤分 |
| `restore` | 人把目标物体移走/移偏 | 放回可用位姿/重新对位，再继续 | T02 水果被推走；T13 试管被移动 | 恢复可操作性 |
| `alternative` | 人拿走目标物体/占用槽位 | 换同类物体/槽位/顺序 | T11 电池被拿走；T24 物品被放回起点 | 避免死磕 |
| `abort` | 不可完成/安全风险 | 安全停住，保留步骤分 | 人把整个容器拿走 | 防止更糟 |

**恢复选择规则（Tier A 启发式）**：
1. 若目标物体仍在工作区且位姿可恢复 → `restore`。
2. 若目标物体被拿走但同类可用 → `alternative`。
3. 若已完成步骤被撤销 → `rollback`。
4. 若只是遮挡/轻推 → `resume`。
5. 否则 → `abort`。

Tier B 用 IA-WM/RRC 在这个规则之上重排；规则仍作为先验/兜底。

### 3.7 单模型合规映射

| 组件 | 是否学习模型 | 是否独立部署 | 合规说明 |
|---|---|---|---|
| WLA-1.0 | 是 | 是（唯一） | 官方 Apache-2.0 基座 |
| LoRA / action expert | 是（同一 checkpoint 的适配器） | 否（合并/同进程） | 属于同一模型 |
| HIM head | 是（轻量头） | 否（同进程） | 挂在 WLA 特征上，输出意图 |
| IA-WM head | 是（轻量头） | 否（同进程） | 挂在 WLA 特征上，输出 latent |
| RRC head | 是（轻量头） | 否（同进程） | pairwise 排序 |
| ITC adapter | 是（LoRA 的一部分） | 否（同进程） | 条件化同一 VLA |
| SSG+/YTE/SVL+ | 否 | 是（代码） | 确定性运行时 |

**审计话术**：“我们提交的是一个 WLA-1.0 模型及其同源轻量预测头；没有第二个策略模型，也没有按任务切换模型。所有动作由同一个 VLA 生成；运行时只做状态管理、安全让位和恢复调度。”

### 3.8 延迟预算

| 路径 | p50 | p99 | 说明 |
|---|---|---|---|
| 正常 chunk | 80–150ms | <300ms | 取决于 action_chunk_size/网络 |
| 干预检测 | <20ms | <50ms | 轻量运动/区域检测 |
| HIM | 30–80ms | <150ms | 冻结特征 + 小头 |
| IA-WM（K=4–8） | 100–250ms | <500ms | 潜空间，无像素解码 |
| RRC | <10ms | <30ms | 小 MLP |
| 恢复 chunk | 80–200ms | <400ms | 同 VLA |
| 单次干预决策路径 p99 | — | **<1.0s** | 不含恢复动作执行；超预算走 Tier A |
| 全 episode p99 | — | **<1.5s** | 监控；触发“可信度”风险则降 K |

**优化手段**：TensorRT/ONNX、FP16/BF16、KV cache、动作块并行、把 HIM/IA-WM 放在与 VLA 同进程的 GPU 上、只对触发状态跑 rollout。

## 4. 数据引擎

### 4.1 HISL：人为干预脚本库

**目标**：把 64 条官方备注变成可检索、可训练、可评测的结构化记录。

**Schema（YAML）**：

```yaml
- id: T27_human_1
  task: stack_bowls_three
  task_index: 27
  variant: human_1
  note_zh: "把粉色碗向下移动"
  note_en: null
  intervention:
    type: translate          # translate | remove | undo | occlude | unknown
    target: pink_bowl
    direction: down          # up/down/left/right/toward/away
    magnitude: small         # small | medium | large
    trigger_step: 1          # 0-based
    timing: before_grasp     # before_grasp | during_transport | after_place
  expected_effect:
    state_delta: "pink_bowl.z -= 5cm"
    goal_changed: false
  recovery:
    primary: restore
    alternatives: [rollback, resume]
    predicates: ["bowl_in_workspace", "bowl_reachable"]
  source:
    url: "https://unibot.unitree.com/tasks_v2/stack_bowls_three/info.json"
    retrieved: "2026-10-25"
    confidence: high
```

**字段说明**：
- `type`：从备注归纳，不保证官方分类；`unknown` 是兜底。
- `trigger_step` / `timing`：用于对齐视频/训练标签；若备注未写，标 `inferred`，置信度降级。
- `recovery`：我们的假设，不是官方答案；用离线/真机验证。

**覆盖**：本轮逐条复核了 T27/T19/T10 的 6 条备注；其余 58 条沿用上一轮抓取，W1 重新核对并补全 schema。**未核对前不要把 64 条都当高置信度。**

### 4.2 64 条脚本的初步分布（待全量核对）

| 类型 | 预估条数 | 例子 | 恢复主选 |
|---|---|---|---|
| `translate`（平移目标物体） | ~30 | T27 human_1、T19 human_1、T10 human_1 | restore |
| `undo`（撤销已完成步骤） | ~20 | T27 human_4、T19 human_4 | rollback |
| `remove`（拿走目标/工具） | ~8 | T11 电池、T24 物品 | alternative |
| `occlude`（遮挡相机/工作区） | ~4 | 人手挡住腕部相机 | resume |
| `unknown`（备注模糊/复合） | ~2 | 同时移动多个物体 | restore→abort |

这些数字是**归纳估计**，不是官方统计；W1 用 64 条全量修正。

### 4.3 合成干预管线（2.5D 编辑）

**目标**：用现有 33k 名义数据生成 3.2k–6.4k 条“人干预”片段，训练 HIM/IA-WM，不依赖大规模真机采集。

**步骤**：

1. **选片段**：每个任务选 50–100 个名义 episode，覆盖不同物体/背景/位置。
2. **分割**：用 SAM2 / GroundingDINO（候选工具）得到目标物体 mask；若数据集有 mask 直接用。
3. **编辑**：
   - `translate`：把目标物体按备注方向平移 3–10cm；补背景/阴影；保持手部/夹爪遮挡合理。
   - `remove`：inpaint 目标区域；模拟“被拿走”。
   - `undo`：取“步骤完成后”的帧，把物体移回“步骤前”的位姿；模拟“被撤销”。
   - `occlude`：在腕部/头部相机上叠加人手/手臂遮挡（可用真实手部视频合成）。
4. **手部插入**：优先用真实人手片段（自采 20–30 条，绿幕/平面背景）做 2.5D 合成；视频扩散模型只用于少量增强，不作为主路径（慢、易伪影）。
5. **标签**：自动写入 `type/target/direction/trigger_step/timing`；用编辑参数做真值，避免人工标注。
6. **质量过滤**：光流一致性、mask 边界、物体尺度、夹爪接触合理性；丢弃明显伪影。
7. **划分**：按任务/方向/物体做 leave-one-out，避免同一 episode 的编辑帧泄漏到训练和验证。

**产出**：
- HIM 训练集：64 脚本 × 50–100 = 3.2k–6.4k 片段；每片段 8–16 帧。
- IA-WM 训练集：同样的片段 + 编辑后的“post-state” latent；不需要像素级真值。
- 恢复对：见 4.5。

**风险**：2.5D 编辑的“人手”不真实，HIM 可能学到编辑伪影而不是干预意图。缓解：真实人手片段 + 域随机化 + 少量真机；离线用真机留出集验证。

### 4.4 真机干预数据（小规模、高价值）

**目标**：400 条真机干预/恢复片段，校准合成→真实的 gap。

**设计**：
- 任务：4 个（T27 叠碗、T19 拉链、T10 插头、T17 合盖）。
- 脚本：每任务 2 条官方备注。
- 次数：每脚本 50 次 → 4×2×50 = 400。
- 操作：实验员按官方备注干预；记录 4 路相机 + proprio + EE + 语言 + 时间戳。
- 标注：干预起止、类型、目标、方向、步骤、恢复模式、结果（成功/失败/步骤分）。
- 采集时间：约 2 天（含复位/标注）。

**用途**：
- HIM 的 true-positive/false-positive 校准。
- IA-WM 的真实 post-state 验证。
- RRC 的恢复结果对。
- 模型卡的“真实数据”证据。

### 4.5 恢复对（recovery pairs）

每条干预记录生成 K 个恢复候选及结果：

| 字段 | 内容 |
|---|---|
| `pre_state` | 干预前/后的观测、EE、夹爪、SSG+ 状态 |
| `intervention` | 类型、目标、方向、步骤、时间 |
| `candidates` | resume / rollback / restore / alternative / abort |
| `outcome` | 成功、步骤分、耗时、碰撞、人工接管 |
| `label` | 最优候选（按成功→步骤分→耗时排序） |

**来源**：
1. 脚本化恢复（Tier A 原语）在仿真/重放里跑 K 个候选。
2. 真机 teleop 纠正（400 条中的一部分）。
3. 合成干预 + 脚本化恢复（用于预训练，不用于最终评估）。

**规模**：64 脚本 × 5 候选 × 20 次重放 ≈ 6.4k 条；真机 400 × 5 = 2k 条。RRC 只需其中 1–2k 对即可起步。

### 4.6 划分与泄漏控制

| 划分 | 训练 | 验证 | 测试 |
|---|---|---|---|
| 任务 | 24 任务 | 4 任务 | 4 任务（含 T27/T19/T10/T17） |
| 干预类型 | translate/undo/remove | occlude | unknown/复合 |
| 方向 | 左/右/下 | 上 | 朝向/远离 |
| 物体 | 已知物体 | 同类新物体 | 未见物体 |
| 背景 | 已知背景 | 新纹理 | 新布局 |

**规则**：同一 episode 的编辑帧只能出现在一个 split；同一任务的 human_1/human_4 不能一条训练一条测试（除非做 leave-one-script-out）；官方备注是公开先验，但**不要把测试任务的备注硬编码进运行时**（Tier A 用通用规则，不用任务特例）。

## 5. 训练配方

### 5.1 Stage 0：基座验证（W1）

- 部署 WLA-1.0-Base，跑通 `example_policy.py` + 本地回放。
- 在 32 任务名义数据上做零样本/少样本评测，记录每任务成功率、步骤分、延迟。
- 确认 action space（joint/ee）、obs_delta_indices、image_resize、chunk size。
- 产出：基线表 + 失败模式分类（放置、抓取、遮挡、指令、干预）。

### 5.2 Stage 1：名义 + 复述 + OPT（W1–W2）

- 数据：33k 名义 + 32×5 复述（官方 `info.json` 的英文复述）+ 物体位姿 token（OPT）。
- 方法：LoRA（r=16–32，alpha=32）微调 WLA；冻结 vision encoder 的前若干层（可选）。
- 目标：在不破坏名义能力的前提下，提升指令/物体/位姿泛化。
- 产出：`WLA-OPT` checkpoint；名义成功率不低于基线。

### 5.3 Stage 2：HIM 头（W3）

- 输入：WLA 视觉 token（pooled）+ 历史 8–16 帧 + 语言 + 官方备注先验。
- 输出：类型（5 类）、目标（物体/容器/步骤）、方向（6 类）、置信度。
- 损失：CE（类型/方向）+ BCE（目标多标签）+ 温度校准/unknown 拒识。
- 数据：3.2k–6.4k 合成 + 400 真机（留出校准）。
- 训练：冻结 WLA，只训 2 层 MLP/Transformer 头；1–2 小时（单卡）。
- 产出：HIM v0；离线准确率/unknown 召回。

### 5.4 Stage 3：IA-WM 头（W4）

- 输入：当前视觉 latent + 干预 token + 候选恢复（模式/目标/方向）。
- 输出：`ẑ(t+Δ)`（post-state latent）、progress（0–1）、碰撞风险、不确定性。
- 结构：4.9M–50M 参数的 latent predictor（MLP/小 Transformer）；不生成像素。
- 损失：latent MSE/cosine + progress 回归 + 碰撞 BCE + 不确定性校准（NLL/分位数）。
- 数据：合成 + 真机 + 恢复对；自监督未来 latent 预测 + 恢复结果弱监督。
- 训练：4–8 小时（单卡/双卡）。
- 产出：IA-WM v0；离线排序 Spearman。

### 5.5 Stage 4：RRC（W4–W5）

- 输入：候选特征（IA-WM 输出 + 规则特征 + 历史）。
- 输出：pairwise 偏好分数。
- 损失：Bradley–Terry / margin ranking；标签来自恢复结果（成功 > 步骤分 > 耗时）。
- 数据：1–2k 恢复对；合成预训练 + 真机校准。
- 训练：<1 小时。
- 产出：RRC v0；离线 top-1 选择准确率。

### 5.6 Stage 5：ITC（W5）

- 输入：HIM 意图 + RRC 选择 + 语言。
- 方法：把结构化干预描述编码成 8–16 个 token，拼进语言上下文；LoRA 微调 WLA 的 action expert。
- 数据：200–500 条恢复 episode（真机 + 高质量合成）。
- 损失：动作模仿（L1/L2）+ 可选的 progress 辅助。
- 训练：1 天（8×H100）。
- 产出：`WLA-ITC`；与 `WLA-OPT` 做消融。

### 5.7 损失与超参（初始建议）

| 组件 | 损失 | 权重 | 备注 |
|---|---|---|---|
| HIM 类型 | CE | 1.0 | 5 类，含 unknown |
| HIM 方向 | CE | 0.5 | 6 类 |
| HIM 目标 | BCE | 0.5 | 多标签 |
| IA-WM latent | cosine + MSE | 1.0 | 归一化 latent |
| IA-WM progress | Huber | 0.5 | 0–1 |
| IA-WM 碰撞 | BCE | 0.2 | 类别不平衡 |
| RRC | margin ranking | 1.0 | pairwise |
| ITC | L1 action | 1.0 | 只对恢复段加权 |
| 正则 | weight decay / dropout | 1e-4 / 0.1 | 小头防过拟合 |

### 5.8 计算与人力

| 项 | 估计 |
|---|---|
| GPU | 8×H100（或 8×A100 80GB）3–5 天；日常 1–2 张 |
| 存储 | 2–3TB（原始 33k + 合成 + 真机） |
| 人力 | 1–2 名工程师 + 1 名真机操作/标注 |
| 软件 | PyTorch、Transformers、SAM2/GroundingDINO（候选）、OpenCV、TensorRT |
| 风险 | WLA 24GB 微调是否支持 LoRA 需实测；合成管线可能比预期慢 |

## 6. 评测协议

### 6.1 离线（W2 起，每周）

| HIM 类型准确率 | 64 脚本留出 | ≥80% | 闭集；unknown 单列 |

### 6.2 本地 TCLB（W4 起，每两周）

- 32 任务 × 5 轴 × 2 次，离线/回放；只做相对比较，不做绝对排名。
- 重点切片：human 轴的“触发率/恢复成功率/额外耗时”；placement 轴的“锁定成功率”。
- 产出：失败模式表（每任务 top-3 失败原因）、恢复模式分布、延迟分布。

### 6.3 平台调试槽（W2/W4/W6）

| 槽 | 任务 | 目的 | 通过标准 |
|---|---|---|---|
| D1 | T27 StackBowls | undo 恢复 | human_4 成功/步骤分明显高于基线 |
| D2 | T19 ZipUp | undo + translate | human_1/4 至少一个恢复成功 |
| D3 | T10 PlugCharger | translate/occlude | 无误碰、无超时、延迟可接受 |
| D4（可选） | T17 CloseBox | 合上再打开 | rollback 恢复 |

- 每槽 10 次（含 2 次 human）；只看机制/延迟/失败模式，不做显著性。
- 每版本最多 1 槽；记录视频/日志/延迟。

### 6.4 全量计分跑（W7/W8）

- 计划 2 次；若只允许 1 次，则 W8。
- 主要终点：human-trial success（64）、overall success（320）、overall step score、time-to-recovery。
- 次要终点：按轴/难度/恢复模式的切片；延迟 p50/p99；碰撞/安全事件。
- 预注册：分析计划在提交前写死；不事后挑任务/指标。
- 预期：human +30–50pp → overall +6–10pp；步骤分 +4–8 分。

### 7.2 I14 · YTE（Yield-to-Think）

- **动机**：人为干扰占 20%；现有 VLA 在人插手时要么继续开环执行（危险/无效），要么直接失败。让位是安全行为，但停顿也是**测试时算力窗口**——可以用这段时间做意图推断和潜空间预判，而不是空等。
- **与现有工作的差异**：Harness VLA/VLA-Corrector 是“失败后恢复”；YTE 是“人一介入就主动让位并利用停顿”，把社会性行为变成计算资源。没有第二个 LLM，没有开放式规划。
- **可行性**：Tier A 只需运动检测 + 冻结/后退 + 规则恢复，1–2 周可跑；Tier B 加 HIM/IA-WM/RRC，4–8 周。延迟预算 2–4.5s/次，180s 足够。
- **资源**：1 名工程师 + 1 名真机操作；Tier A 无需新 GPU；Tier B 8×H100 3–5 天。
- **步骤**：① 干预检测/工作区定义；② 让位轨迹（后退 5–10cm、速度限制）；③ 人手离开 dwell；④ 恢复原语；⑤ 预算守卫；⑥ 与 SSG+ 对接。
- **风险**：让位碰撞、超时、被人误解为“逃避”；用安全轨迹、总预算、日志缓解。
- **状态**：设计完成，待 W1 实现 Tier A。

### 7.3 I15 · HIM（Human Intervention Model）

- **动机**：官方备注（很可能）把干预变成 64 个闭集脚本；不需要开放世界意图理解，只需要“类型/目标/方向/步骤”的分类 + unknown 兜底。
- **差异**：Correction Timing/GUIDER/HINT 多做人机协作或长程任务；HIM 专门利用**赛制公开的备注先验**，把“意图”压缩成可审计的 5+6+多标签结构。
- **可行性**：合成 3.2k–6.4k + 真机 400；冻结 WLA 特征 + 小头；单卡 1–2 小时。离线 ≥80% 是合理目标（闭集、单任务 2 类）。
- **资源**：合成管线 1 人 1–2 周；真机 2 天；GPU 1 张。
- **步骤**：① HISL schema/64 条核对；② 2.5D 编辑；③ 标签自动生成；④ 头训练/校准；⑤ unknown 拒识；⑥ 留出任务验证。
- **风险**：合成域差、备注与实际评测不一致、unknown 过多；用真机校准 + 保守阈值 + Tier A 兜底。
- **状态**：待 W3 实现。

### 7.4 I16 · IA-WM（Intervention-Aware World Model）

- **动机**：恢复候选有好有坏；像素级世界模型太慢，潜空间 rollout 可以在 100–300ms 内给 K 个候选打分。
- **差异**：AHEAD/VeriVLA 是通用动态/验证；IA-WM 条件在“干预类型/目标/方向”上，专门预测 post-intervention latent + progress + 碰撞，不生成像素。
- **可行性**：4.9M–50M 参数；冻结 WLA 特征；合成 + 真机；单卡 4–8 小时。风险是真实 post-state 的 latent 难预测，先做排序不做真值。
- **资源**：1 名工程师 2 周；GPU 1–2 张；数据复用 HIM 管线。
- **步骤**：① 定义候选恢复；② 采集合成/真机 post-state；③ 训练 latent predictor；④ 加 progress/碰撞头；⑤ 与 RRC 对接；⑥ 离线 Spearman 验证。
- **风险**：幻觉/排序差、域 gap；用“只排序 + 不确定性 + 启发式兜底”缓解；Spearman <0.3 关闭。
- **状态**：待 W4 实现。

### 7.5 I17 · RRC（Relative Recovery Critic）

- **动机**：绝对价值回归在稀疏成功信号下不稳；pairwise 比较“哪个恢复更好”更接近可得标签（成功/步骤分/耗时）。
- **差异**：VLA-ATTC 做动作块相对 critic；RRC 做**恢复模式**的相对排序，输入是 IA-WM 特征 + 规则特征。
- **可行性**：1–2k 恢复对即可；小 MLP；<1 小时训练。标签来自脚本化恢复 + 真机 teleop，成本可控。
- **资源**：复用 4.5 的恢复对；GPU 1 张。
- **步骤**：① 定义偏好顺序（成功 > 步骤分 > 耗时 > 安全）；② 构造 pairs；③ Bradley–Terry/margin 训练；④ 校准；⑤ 与 IA-WM 联合/消融。
- **风险**：标签噪声、候选覆盖不足；用多标注/规则先验/不确定性缓解。
- **状态**：待 W4–W5 实现。

### 7.6 I18 · ITC（Intervention Token Conditioning）

- **动机**：恢复不应该由外挂 planner 生成动作；把干预意图/恢复模式编码成 token，拼进同一 VLA 的语言上下文，让模型自己生成恢复动作。
- **差异**：HINT 用意图作为稀疏中间表示；ITC 把意图**条件化到动作生成**，且只微调同一 checkpoint 的 LoRA/action expert，符合单模型。
- **可行性**：200–500 条恢复 episode；LoRA 1 天（8×H100）；风险是数据少/过拟合，用合成预训练 + 真机校准 + 低 rank。
- **资源**：8×H100 1 天；真机 200–500 条（可与 4.4 复用）。
- **步骤**：① 定义 token schema；② 构造恢复 episode；③ LoRA 微调；④ 与 prompt-only 消融；⑤ 延迟/动作平滑检查。
- **风险**：破坏名义能力、动作抖动；用低 LR/rank、混合名义数据、SVL+ 验证缓解。
- **状态**：待 W5 实现。

### 7.7 I19 · Empathic Yield（低优先）

- **动机**：让位时头/ gaze 朝向人、慢速后退，可能减少碰撞、让人更愿意配合；这是“行为共情”的最小表达。
- **差异**：不做情绪识别/表情/语气；只做可被评分间接奖励的动作（安全、可预测、不抢占）。
- **可行性**：无需训练；在 YTE 轨迹上加头部朝向/速度限制；1–2 天。
- **资源**：无额外 GPU；真机调试。
- **步骤**：① 定义“朝向人”的头部姿态；② 慢速后退；③ 不遮挡人/不碰人；④ 消融“有/无朝向”。
- **风险**：脚本化评测者不因表情改变行为；收益可能只在碰撞/无效动作上。**若 debug 无可见收益，砍掉。**
- **状态**：低优先，W6 再看。

### 7.8 砍掉/降级的内容与理由

| 内容 | 处置 | 理由 |
|---|---|---|
| 情绪识别/表情/语气 | 砍 | 无评分信号；评测者按剧本行动 |
| 第二个 LLM planner | 砍 | 违反单模型严格解释；延迟/动作不可控 |
| 每 episode 梯度更新 | 砍 | 延迟/可信度风险；180s 预算 |
| 全 32 任务高保真孪生 | 砍 | 成本过高；用 2.5D + 4 任务真机 |
| 自由仿真数据 | 砍 | 域 gap；优先真实+2.5D |
| 运行时 MPC/仿真 RL | 砍 | 延迟/工程复杂度 |
| TCLB 绝对排名 | 降级 | 榜单占位；只做相对比较 |
| L2L/TLE-ACP-GF/AH-TP | 降级 | 保留但不作为主攻；资源让给 YIELD |
| FLEET | 保留 | 发布纪律/合规，不占研究预算 |
