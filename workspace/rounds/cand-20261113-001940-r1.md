# 第 3 轮迭代（灵感循环 v3：「ROS」×「意图理解」）—— 从「事后检测撤回」到「事前预测意图的主动仲裁」

> **承接 v2，不推倒。** v2 把 `human_*` 读成「反向撤回」，给出「检测 `regressed` → 重做」的反应式闭环，并以 Gazebo 造数据 + 计分神谕 + 自适应块长支撑。本轮两个灵感词恰好补上它最硬的两个缺口：
> - **「意图理解」**：人为干扰不是随机噪声，而是**有目标的干预**（撤回 / 搬移 / 拿走 / 遮挡 / 递物 / 协助）。既然有目标，就能**在动作完成前预测**，并选择「抢跑 / 让行 / 稳住 / 重新接地 / 配合」——而不是一律重做。
> - **「ROS」**：把 v2 散落的验证器、技能图、延迟工程、仿真 oracle 收拢成一条**可观测、可回放、可隔离的运行时契约**。关键事实：选手的推理服务跑在**自己的服务器**上，评测只约束 `get_action` 语义；因此 ROS 2 可作为**服务端内部架构**合法存在，不必碰评测机的接口红线。

---

## 0. 直觉先行（30 秒版）

- **ROS 的直觉**：它不是「又一个仿真器」，而是机器人软件的**神经系统**——节点用带类型的消息说话，QoS 约定可靠性，TF 统一坐标系，rosbag2 把一切录下来重放。它最大的价值不是「能跑」，而是**能被看见、能被复现、能被隔离**。
- **意图理解的直觉**：看到一只手伸向刚叠好的毛巾，你不会等它翻开再重叠。你会**预判它要翻开**，于是要么赶紧把最后一步做完（抢跑），要么先松手让它翻完再重来（让行），要么用夹爪把毛巾压住（稳住）。这就是「反应」与「预测」的差别。
- **合起来**：ROS 提供「意图总线 + 行为树 + 回放」的骨架；意图理解提供「该抢跑还是该让行」的决策内容。v2 的 `regressed→redo` 退化为**低置信度兜底**。

## 1. 对 v2 清单的诊断（哪些该升级、哪些该并入）

- **必须升级（认知层）**：UIP-01′/UIP-09′ 是**反应式**的——只有等子目标从 done 回退到 undone 才动作，此时「浪费的动作」已经发生。且它把 `human_*` 当成单一类型「撤回」，忽略 `info.json` 里其实存在**搬移、拿走、遮挡、挪底座、协助**等异质意图，而这些的最优响应完全不同（见 §3 表）。
- **必须升级（架构层）**：UIP-14 是「扁平路由」，没有反应式仲裁；UIP-08′ 的端口隔离、UIP-13 的块长调度、UIP-15 的延迟护栏各自为政，缺少一条统一的、可观测的运行时。ROS 2 的节点/QoS/生命周期/组合/introspection 正好是这条运行时。
- **合并**：UIP-12（脚本扰动工厂）→ 升级为 **rosbag2 反事实拼接**（录一次真实 episode，离线拼接不同人类意图并重放）；UIP-11（Gazebo 判分）接入同一节点图，经 `ros_gz_bridge` 与真机共享仲裁/验证代码，消除「两套实现」的漂移。
- **保留**：UIP-02′（计分安全网）、UIP-05（语言→可供性，升级为 UIP-21 的计划编译）、UIP-13（块长调度）。
- **修剪**：「外部 VLM 做意图理解」不再考虑——单模型合规风险 + 延迟不可控。意图头必须是**共享骨干上蒸馏出的小头**。

## 2. 两个灵感词：先直觉，再严谨定义

### 2.1 「ROS」→ 不是仿真器，而是**运行时契约**

**直觉。** ROS 之于机器人，像 HTTP + pcap 之于 Web：它规定「谁用什么格式说什么」，并让你能抓包、回放、看延迟。它不会替你把策略变聪明，但它能让一个复杂系统**不再靠猜**。

**严谨定义。** ROS 2 是**数据分发中间件 + 组件模型**：节点（node）通过带类型接口（topic/service/action）通信；QoS（reliability/durability/history/deadline/liveliness）把「实时性」从口号变成**可声明、可测量的契约**；`tf2` 维护带时间戳的坐标变换树；`rosbag2` 提供确定性记录/回放；`lifecycle` 管理冷启动与状态迁移；`composition` 支持进程内零拷贝。它**不是**控制算法，也**不提供硬实时保证**。

**本轮对 ROS 的三个用法（按合法性排序）：**

1. **服务端内部运行时（主用法，合法）**：评测只调用 `get_action`，选手服务器内部可以是一个 ROS 2 节点图。观察进入 `/obs`，意图头发布 `/intent_belief`，验证器发布 `/progress`，行为树仲裁器发布 `/arbiter_cmd`，技能 action server 产出动作块。日志节点旁路写 rosbag2。**每端口一个 namespace/context**，天然满足「N 端口状态隔离」。
2. **离线影子运行时（最稳）**：Gazebo（`ros_gz_bridge`）+ 同一仲裁器，对任意策略 rollout 做计分代理与反事实回放。
3. **可复现性（科研价值）**：每次评测落 rosbag2，事后可精确重放到「干扰发生前 200 ms」，做意图消融与决策后悔值分析。

**约束（必须写死在设计里）**：ROS 2 不是硬实时；热路径要进程内组合 + 零拷贝 + 有界队列 + 独立 executor；若评测服务器不允许/装不上 ROS，必须能**降级为同接口的 asyncio 进程内总线**，算法不依赖 ROS。

### 2.2 「意图理解」→ 把人类当成**有目标的理性规划者**，而不是扰动源

**直觉。** 人不会随机地把毛巾翻开；他有一个**目标状态**，并在用一条**低成本的轨迹**去实现它。看到前半段轨迹，就能反推最可能的那个目标。

**严谨定义（逆规划 + POMDP）。** 令世界状态 `x_t`，人类目标 `ι ∈ I`（干预意图），人类按 Boltzmann 理性策略行动：

```
π_H(a | x, ι) ∝ exp( β · R(x, a, ι) )
```

机器人看不到 `ι`，只能看到图像 `o_t`，于是维护意图信念

```
b_t(ι) = P(ι | o_{1:t}) ∝ P(o_t | ι, o_{1:t-1}) · Σ_{ι'} P(ι | ι') b_{t-1}(ι')
```

**关键先验来自规则侧证据**：每个任务的 `info.json.generalization.human_*` 给出了该任务**允许的干预类型与对象**。例如 T19 的先验几乎只落在 `UNDO(zip)`，T05 落在 `HANDOVER/insert`。这不是「作弊」，而是**把题目给定的对手模型用满**——先验 `P(ι)` 按任务条件化，极大压缩意图搜索空间。

**意图是异质的，响应也必须异质**（这是 v2 缺失的核心）：

| 推断意图 `ι` | 语义 | 最优响应 | 典型任务 |
|---|---|---|---|
| `UNDO(g)` | 把已完成子目标 g 撤回 | **抢跑 / 让行 / 稳住**（RYG 三选一） | T14 拧回、T16 翻开、T17 再打开、T19 拉开、T27 拿下第二个 |
| `RELOCATE(o, r)` | 把物体/底座挪到别处 | **重新接地**目标位姿，已完成步不重做 | T01/T02/T06 物体平移、T25 挪底座 |
| `REMOVE(o)` | 把必需物拿走 | **保前置步骤分**，再尝试替代方案；不可硬刚 | T12 中途把锁拿走 |
| `OCCLUDE(o)` | 遮挡目标/相机 | **等待或换视角**，禁止误判为 `fail` | T29 外壳盖移开 |
| `HANDOVER(o)` | 主动把物体递给机器人 | **张开夹爪配合**，不要抢 | T05/T10 道具手 |
| `ASSIST(g)` | 帮你完成某步 | **接受协助、跳过该子目标** | 人为推进类干扰 |
| `NONE` | 无干预 | 正常执行 | 多数 episode |

## 3. 形式化：意图条件化的「抢跑-让行-稳住」仲裁

设当前子目标 `g`，分值 `v(g)`（取自 32 任务计分表）；预测机器人完成耗时 `τ_R`，人类撤回完成耗时 `τ_H`（由意图头回归的 deadline）。记 `p = P(τ_R < τ_H)`，`w` = 被撤回时浪费的动作代价，`c_r` = 重做该子目标的代价，`λ` = 延迟权重。

```
U_race  = v(g) − (1−p)·(w + c_r) − λ·E[t]          # 抢跑：赢则落袋，输则白干+重做
U_yield = v(g) − c_r − λ·E[t']                      # 让行：等它撤完再重做，不做无用功
U_guard = v(g) − c_hold − λ·E[t''] − risk           # 稳住：夹住/压住，使撤回物理上难以发生
```

忽略时间项，`U_race ≥ U_yield` 的阈值是一个极简的**代价比**：

```
p* = w / (w + c_r)        # 抢跑当且仅当 p ≥ p*
```

直觉：重做越贵（`c_r` 大），越值得抢跑；白干越便宜（`w` 小），越值得抢跑。若 `p` 低于阈值且物体可稳定夹持，则「稳住」：只稳定**自己已抓取的对象**，绝不物理阻挡人手（安全/伦理红线）。

**决策复杂度可控**：意图头输出 `|I|` 个 logits（几十类，按任务裁剪），仲裁只需比较 3 个宏动作的期望效用，无需在线求解完整 POMDP；意图头每 k 步才更新一次（与 UIP-13 块长对齐）。

## 4. 瓶颈假设

- **H5（可预测性）**：人为干预是**意图结构化**的，且 `info.json` 给出了任务级先验；「短视觉历史 + 任务先验」足以把 top-1 意图准确率抬到显著高于随机，从而让 p 的估计有用。
- **H6（主动优于反应）**：当 `p` 越过阈值 `p*` 时，主动 RYG 的期望步骤分严格高于「一律 `regressed→redo`」；阈值附近则由 UIP-20 退回反应式。
- **H7（运行时收益）**：ROS 2 服务端运行时能把「多端口隔离 + 回放 + 延迟可观测」的工程成本显著降低，且热路径开销可控制在块周期的 10–20% 以内（用组合/零拷贝/有界队列）。
- **H8（计划即意图）**：32 张计分表就是任务的「标准意图分解」；把语言编译成以计分步为节点的计划 DAG（UIP-21），可消除语言歧义并直接对齐步骤分。
- **H9（反事实可行）**：真实 episode 的 rosbag2 记录 + 离线拼接合成干预，能在**不重训策略**的前提下，为意图头/仲裁器提供足量反事实监督。

## 5. 候选合并 → v3 清单（详见产物区）

围绕两词发散 8 个草案，合并为 v3：旗舰 **UIP-16 IC-RYG**（意图条件化抢跑-让行-稳住），架构底座 **UIP-17 RIB**（ROS 2 意图总线运行时），并由 **UIP-18 BT-SG**（意图装饰行为树）、**UIP-19 RCIC**（rosbag2 反事实课程）、**UIP-20 IAG**（意图歧义安全阀）、**UIP-21 LIC**（语言→计分计划编译器）四条腿支撑；v2 的 `regressed→redo` 整体降级为「意图置信度不足时的兜底」。

## 6. 本轮最大风险

**一句话**：把「意图」当成可观测变量是危险的——视觉证据稀疏、人为干扰可能被刻意设计成不可预测，意图先验一旦错配，主动抢跑/让行会比被动重做更伤步骤分；同时 ROS 运行时是自建假设，若评测服务器不允许或跑不动，整套架构收益无法兑现。

## 1. 旗舰深潜：UIP-16 · IC-RYG（Intent-Conditioned Race-Yield-Guard）

### 1.1 机制

每次拿到新观察，先做一次**轻量意图推断**，再对当前子目标 `g` 选择宏动作：

```
ι̂ ~ b_t(ι)                     # 任务先验 × 短视觉历史
switch ι̂.type:
  HANDOVER            -> cooperate        # 张爪配合
  ASSIST(g)           -> accept_help      # 跳过 g，计入步骤分
  OCCLUDE             -> observe          # 等待/换视角，不判 fail
  RELOCATE(o,r)       -> reground(r)      # 只更新目标位姿，不重做已完成步
  REMOVE(o)           -> bank_and_improvise  # 先锁前置分，再找替代
  UNDO(g)             -> race / yield / guard  # 见下
  NONE                -> normal_exec
```

`UNDO` 分支用 §3 的效用比较：`p ≥ p*` 抢跑，`p` 低且可稳定夹持则稳住，否则让行。

### 1.2 与 v2 的本质差异

- v2：**状态机只有「当前子目标做没做」**；v3：**状态机之外多了一个「人类想干什么」的信念维度**。
- v2：撤回发生后重做（浪费已发生）；v3：撤回**完成前**决策（浪费可避免）。
- v2：所有干扰同一套响应；v3：六类意图六种响应（尤其 `RELOCATE/REMOVE/OCCLUDE/HANDOVER` 根本不该重做）。
- v2：单一视觉判据；v3：意图头输出**类型 + 目标 + deadline + 置信熵**，直接喂给决策与安全阀。

### 1.3 可行性 / 资源

- **可行性中高**：意图头是共享骨干上的小分类+回归头（单模型合规）；先验来自 `info.json`；`action_chunk_size`、`reset()`、`get_action` 全在接口内。
- **资源**：1 张推理卡；Gazebo/rosbag2 离线算力；无需改评测接口。
- **数据**：真实 episode 用 rosbag2 记录；合成干预用 UIP-19 拼接。**评测期不需要人类标注**，只在线推断。

## 2. UIP-17 · RIB（ROS 2 Intent Bus Runtime）

### 2.1 节点图（服务端内部，评测只看到 `get_action`）

```
[评测机] --HTTP/JPEG q95--> [选手推理服务器]
                              │
              ┌───────────────┴────────────────┐
              │   ROS 2 图（每端口独立 namespace） │
              │  /p{i}/obs ──► /p{i}/intent      │
              │        │            │            │
              │        ▼            ▼            │
              │   /p{i}/progress   /p{i}/arbiter │
              │        └────► /p{i}/skill (action)│
              │                     │            │
              │                     ▼            │
              │              /p{i}/action_chunk  │──► get_action 返回
              │  /p{i}/diag ◄── 全节点            │
              │  rosbag2 旁路：obs/action/belief/progress │
              └────────────────────────────────┘
```

- **每端口隔离**：`/p{port}/...` namespace + 独立 `rclcpp::Context`（或独立进程）+ 独立 executor。天然满足 README 「N 端口状态必须隔离」。
- **TF 树**：`world → table → object`、`base → head_cameras/wrist_cameras`、`base → gripper`。位置泛化/背景泛化直接受益：一切判断在**对象相对坐标系**里做，而不是像素坐标。
- **QoS**：命令类 `reliable` + `keep_last(1)`；高频感知 `best_effort` + `keep_last(1)` + `deadline`；诊断 `transient_local`。用 QoS 把「延迟/丢帧」写成可测契约。
- **组合与零拷贝**：感知→意图→仲裁尽量同进程 `component` + intra-process，避免序列化开销。
- **可观测**：`ros2 topic delay`、`ros2 topic hz`、tracing；每端口 p50/p95 延迟与抖动进 `/diag`，直接对应榜单可信度口径。

### 2.2 部署二分（把「开发底座」与「评测载荷」分开，避免合规争议）

| 层 | 内容 | 是否进评测 |
|---|---|---|
| 评测载荷 | 骨干 + 意图头 + 验证器 + 仲裁器 + 行为树 + **无 ROS 的 asyncio 总线** | ✅ 唯一必需 |
| 服务端运行时 | ROS 2 包装、rosbag2、TF、诊断 | ⭕ 可选（服务器允许时启用） |
| 离线影子 | Gazebo + `ros_gz_bridge` + 同一仲裁器 | ❌ 仅开发/评估 |

> **红线**：绝不要求评测机装 ROS；绝不用 ROS 改变 `get_action` 的语义、形状、dtype、块长。ROS 是「我们自己服务器内部的工程」，不是接口扩展。

### 2.3 延迟预算（目标，非承诺）

- 骨干前向占大头；意图头 + 验证器 + 仲裁 + BT 目标 **< 10–20% 块周期**，p95 抖动 < 一个控制步。
- 热路径有界队列 + 只保留最新一帧；日志/rosbag2 走旁路线程/进程，不阻塞推理。
- 若 ROS 开销超标 → 自动降级 asyncio 总线（同一接口，`--no-ros`）。

## 3. UIP-18 · BT-SG（Behavior-Tree Skill Graph）

### 3.1 树结构（`BehaviorTree.CPP` 风格）

```
ReactiveFallback
├── Sequence [ IntentIs(HANDOVER),      CooperateNode ]
├── Sequence [ IntentIs(OCCLUDE),       ObserveNode ]
├── Sequence [ IntentIs(RELOCATE),      RegroundNode ]
├── Sequence [ IntentIs(REMOVE),        BankThenImproviseNode ]
├── Sequence [ IntentIs(UNDO),          RaceYieldGuardNode ]
│     ├── Race   (p ≥ p*)
│     ├── Guard  (可稳定夹持 且 p < p*)
│     └── Yield  (否则)
└── SkillSequence(plan_dag)          # 正常路径：抓→放→插→…
```

- **节点 = 技能**（抓/放/插/倒/拉链/折叠/堆叠/分拣/开合/挑取），对应 v2 的 10 个技能模块。
- **装饰器 = 意图条件**：`IntentIs(...)`、`BeliefEntropyBelow(τ)`、`SafetyOK()`。
- **反应式**：意图变化时，`ReactiveFallback` 在下一 tick 抢占当前分支，无需重启整个计划。
- **与计分对齐**：`SkillSequence` 的 tick 顺序即计分步顺序；每完成一个技能节点，`/progress` 发布一次 `done`，步骤分即时落袋（UIP-02′）。

### 3.2 与 UIP-14 的差异

UIP-14 是「先路由到某技能，再顺序执行」；BT-SG 把**路由与仲裁合并成一棵可抢占的树**，意图是运行期信号而非一次性选择，且天然支持「执行中被打断→换分支」。

## 4. UIP-19 · RCIC（Rosbag2 Counterfactual Intent Curriculum）

### 4.1 机制

1. **录**：每次真实/仿真 episode 用 rosbag2 记录 `/obs`、`/action_chunk`、`/progress`、`/intent_belief`（时间戳对齐 TF）。
2. **切**：在「子目标刚完成」的时刻 `t*` 前 200 ms 切片。
3. **拼**：从 Gazebo/DRF 生成的「干预轨迹库」中取一条意图 `ι`（拧回/翻开/拉开/拿走/挪底座/递物），拼接到 `t*` 之后。
4. **放**：重放到仲裁器，得到「若人类意图是 ι，IC-RYG 会怎么做」的反事实轨迹与步骤分。
5. **训**：用（真实历史, 反事实标签）训练意图头与仲裁阈值 `p*`；**不重训主策略**。

### 4.2 与 UIP-12 的差异

UIP-12 是「在仿真里从零造 (干扰前→撤回→恢复) 三元组」；RCIC 是**在真实记录上做反事实外科手术**，保留真实视觉/接触纹理，只替换人类意图分支——训练与评测的**观测分布更接近**，缓解纯仿真的 sim-to-real 偏移。

### 4.3 风险

拼接处的时序/物理不连续会造假样本 ⇒ 只在「子目标边界」拼接（此时机器人已松手、场景准静态），并用 TF 时间戳做一致性校验。

## 5. UIP-20 · IAG（Intent-Ambiguity & Compliance Governor）

```
if H(b_t) > τ_H:                 # 意图太模糊
    action = observe_or_continue # 先观察/正常执行，不抢跑、不猛重做
elif p* boundary and b_t(UNDO) mid:
    action = reactive_regressed_redo   # 退回 v2 兜底
else:
    action = IC-RYG
# 全局护栏：
#  - 最大重做次数 / 延迟预算 / 抖动上限（继承 UIP-15）
#  - guard 仅稳定自身已抓取物，绝不阻挡人手（安全红线）
#  - 意图头必须是共享骨干的内部头；禁止外部 VLM（单模型合规）
```

- **作用**：防止「意图误判 → 反复抢跑/让行」造成的步骤分震荡；熵是天然的「该不该相信意图」的开关。
- **可测**：`overreaction rate`（错误主动干预占比）、`missed-undo rate`、`decision regret`（相对全知仲裁器）。

## 6. UIP-21 · LIC（Language → Scoring-Plan Compiler）

- **机制**：把 `observation.language` 编译成**带成功谓词的计划 DAG**：
  `parse(lang) → task_id/意图 → 查 32 任务计分表 → 步骤节点 + 分值 + 几何/语义成功谓词 → 交给 BT-SG`。
- **为什么是「意图理解」**：语言的真实意图由**计分口径**定义；直接用官方计分表作计划模板，等于拿到「出题人的意图」，消除自由语言到动作的歧义。
- **未见物品/背景**：计划结构不变，只把节点里的对象/位姿换成**视觉 grounding**（继承 UIP-05）。
- **与 UIP-02′ 的差异**：UIP-02′ 是「按分值时序推进」的策略原则；LIC 是「把语言编译成可执行、可验证的 DAG」的编译器，二者合流。

## 7. 关键伪代码

### 7.1 意图信念 + 仲裁（UIP-16 / 20）

```python
class ICRYGArbiter:
    def __init__(self, intent_head, verifier, bt, plan,
                 w=0.3, c_redo=0.6, ent_thr=0.8,
                 max_redo=2, latency_budget_ms=200):
        self.h = intent_head; self.v = verifier; self.bt = bt
        self.w = w; self.c_redo = c_redo; self.ent_thr = ent_thr
        self.p_star = w / (w + c_redo)          # 抢跑阈值

    def reset(self):
        self.g = 0; self.redo = 0; self.b = None

    def act(self, obs):
        self.b = self.h.update(obs, self.plan.task_prior, self.g)
        i_hat, conf, ent = self.b.top()
        if ent > self.ent_thr:                   # UIP-20：太模糊
            return self._reactive_fallback(obs)
        t = i_hat.type
        if t == "HANDOVER":   return self._cooperate(obs)
        if t == "ASSIST":     return self._accept_help(obs)
        if t == "OCCLUDE":    return self._observe(obs)
        if t == "RELOCATE":   return self._reground(obs, i_hat)
        if t == "REMOVE":     return self._bank_then_improvise(obs)
        if t == "UNDO" and i_hat.target == self.g:
            p = self.h.win_prob(self.g, i_hat.deadline, obs)
            if p >= self.p_star:
                return self._race(obs)           # 抢跑
            if self._can_guard(self.g, obs):
                return self._guard(obs)          # 稳住（只夹自己的物体）
            return self._yield(obs)              # 让行后重做
        return self._execute(obs)                # NONE / 正常

    def _reactive_fallback(self, obs):
        st, _ = self.v(obs, self.plan.node(self.g))
        if st == "regressed" and self.redo < self.max_redo:  # v2 兜底
            self.redo += 1
            return self._redo(self.g, obs)
        if st == "done":
            self.g += 1; self.redo = 0
        return self._execute(obs)
```

### 7.2 意图头（共享骨干上的内部头）

```python
class IntentHead(nn.Module):
    # 输入：骨干特征 z_t + 短历史 z_{t-h:t} + 任务先验 prior(task)
    # 输出：type logits、target logits、deadline 回归、熵
    def forward(self, z_hist, prior):
        x = self.trunk(z_hist)                  # 轻量时序编码
        logits_t = self.type_head(x) + torch.log(prior.type + eps)
        logits_o = self.target_head(x) + torch.log(prior.target + eps)
        deadline = F.softplus(self.time_head(x))
        return logits_t, logits_o, deadline
    # 训练：真实 rosbag2 边界切片 + RCIC 反事实标签；蒸馏自骨干，不引入外部模型
```

class ArbiterNode(rclpy.Node):

        self.declare_parameter("port", 0)

### 7.4 决策阈值（推导备忘）

```
U_race  = v(g) − (1−p)(w + c_r)
U_yield = v(g) − c_r
U_race ≥ U_yield  ⇔  p ≥ w / (w + c_r) = p*
```

例：`w=0.3, c_redo=0.6 ⇒ p*=1/3`；若重做极贵（`c_r` 大），阈值趋近 0，几乎总该抢跑；若白干极便宜（`w→0`），阈值趋近 0，同样抢跑（因为输了也没损失）。

## 9. 合规、安全与风险

- **单模型合规**：意图头、验证器、技能头全部**共享一条骨干**；蒸馏得到，不引入外部 VLM/API；ROS 只是服务端内部工程，不是第二个模型。
- **接口红线**：`get_action` 的语义、形状、dtype、块长严格按 README §3；ROS 层不得改变返回值。
- **安全红线**：`guard` 只允许「稳定自己已抓取的物体」，**绝不物理阻挡人手**；`race` 不得以碰撞风险为代价。
- **ROS 依赖风险**：评测/服务器可能不允许 ROS ⇒ 必须保留 `--no-ros` 的 asyncio 同接口实现；ROS 收益（回放/观测/隔离）只在允许时兑现。
- **意图误判风险**：稀疏视觉 + 对手可能刻意不可预测 ⇒ 用 IAG 熵门控 + v2 反应式兜底；先验错配时退回「不做主动仲裁」。
- **手册缺口**：5 轴中的位置/干扰物/背景、评测轮次/时限/控制频率仍未从飞书正文核实（2026-11-12/13）。

## 11. 本轮最大风险 & 押注

**一句话**：把「意图」当成可观测变量是危险的——视觉证据稀疏、人为干扰可能被刻意设计成不可预测，意图先验一旦错配，主动抢跑/让行会比被动重做更伤步骤分；同时 ROS 运行时是自建假设，若评测服务器不允许或跑不动，整套架构收益无法兑现。

**→ 押注：UIP-16 IC-RYG × UIP-19 RCIC 的「意图条件化恢复闭环」**——由 UIP-21 的计划 DAG 提供任务先验、UIP-20 的熵门控兜底、UIP-17/18 提供可观测运行时。它把 v2「白纸黑字的撤回型干扰」从**被动重做**推进到**主动决策**，且始终保留「意图不可信就退回反应式」的安全退路。
