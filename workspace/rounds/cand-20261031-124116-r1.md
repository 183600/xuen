# 第 13 轮 · 新灵感循环 R1 · FUSE-CAL / FUSE-FLEET：让同一个 WLA 在 N 台机器人上看到同一个世界

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是灵感循环第 1 轮，三个词是「传感器融合」「多机评测」「排行榜」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是在它们前面加一层：**先让模型看到同一个世界，再谈 5 步闭环。**

## 0. 先给结论：缺的不是更大的 VLA，而是“同一个世界”的观测

第 12 轮 CHUNK-SERVO 解决的是执行层：30 步规划、5 步视觉伺服、演示检索相对目标、数字孪生标定。本轮回到更前置的问题：

> **如果 VLA 看到的世界本身就不是同一个世界，伺服再快也只是在错误坐标系里修正。**

三个随机词不是三个独立方向，而是同一个缺口的三个侧面：

1. **传感器融合**：挑战赛给四路 RGB + 本体感觉，却没有 depth、camera_info、force/torque、tactile。四张图不是“四个视角”，而是一个**需要在线标定的观测系统**；最后 3 厘米既缺几何，也缺接触状态。
2. **多机评测**：评测跨 N 台机器人，每台机器人一个固定端口（8765 起连续 N 个）。N 套相机安装、夹爪、网络延迟、控制响应可能不同；同一个 WLA 必须在**每端口指纹不同**的情况下看到同一个世界。
3. **排行榜**：榜单是 8 个预览模型、256 条预览 runs，JSON 由 `gen_leaderboard.py` 生成；步骤分与成功率几乎完全线性，跨模型任务相关只有 0.098，官方难度与预览成功率相关 -0.232。它不是 SOTA，也不是难度表，只能当**弱先验**。

所以本轮的押注是 **FUSE-CAL / FUSE-FLEET**：

> 用**右头相机**（WLA 当前不用）做双目几何，用**双腕 + 本体感觉**做伪触觉，用**每端口机器人指纹**做规范化；把四路 RGB + 本体感觉变成可自校准的米制几何与接触证据，喂给**同一个 WLA checkpoint**；CHUNK-SERVO 继续做 5 步执行；排行榜只当噪声先验，工程按成功优先的官方 rubric 组合投。

一句话：**把“多机评测”从方差来源变成观测优势，把“没有触觉”变成可计算的伪触觉，把“排行榜”从难度表降级为弱先验。**

本轮的新颖性主张（经本轮文献复核，不声称绝对首创）：

1. 把**每任务/每机器人的相机参数差异**当作测试时规范化问题，而不是训练时数据增强；用 WLA 闲置的右头相机做双目几何，用每端口指纹把观测映射到同一个虚拟相机。
2. 在没有触觉的 API 下，用**本体跟踪残差 + 夹爪闭锁 + 腕部光流**做确定性伪触觉，不训练第二个接触分类器。
3. 把**多机评测**建模为“每端口指纹 + 共享模型规范化”，并把**排行榜**降级为弱先验，用官方 rubric 做成功优先的组合预算。

## 1. 三个灵感词如何落到同一个方案里

| 灵感词 | 真实缺口 | 落到哪里 | 不做什么 |
|---|---|---|---|
| **传感器融合** | 四路 RGB 无 depth/camera_info；头双目参数跨任务变化；腕部有内参但未统一；无 force/tactile | FUSE-GEOM：右头双目 + 双腕 + 本体感觉 → 在线自校准的米制几何；FUSE-TOUCH：跟踪误差 + 夹爪闭锁 + 腕部光流 → 伪触觉 | 不训练独立深度模型；不训练第二个接触分类器；不做力/触觉闭环（API 没有） |
| **多机评测** | N 台机器人、N 个端口；每端口独立 episode；相机/夹爪/延迟可能不同 | FLEET-FINGERPRINT：每端口标定/指纹 + 规范化；共享一个 WLA；每端口状态隔离 | 不假设 N 固定；不把某台机器人的标定硬编码给所有端口；不做 N 份不同模型 |
| **排行榜** | 8 个预览模型、256 条 runs；步骤分合成；任务相关低；官方难度与预览成功率不一致 | RUBRIC-PORTFOLIO：榜单只当弱先验；成功优先；步骤分只做 tie-break；单任务通道做配对 A/B | 不按预览榜单任务排名分配工程；不把 29.7% 当 SOTA；不把步骤分当成功率 |

## 2. 本轮新核实/修正的事实（只列会改变方案的）

### 2.1 规则与接口：单模型、32 任务、10 次/任务、N 端口、chunk 开环

官方参赛手册（2026-10-31 经 `r.jina.ai` 复核）与提交模板给出：

- 所有任务须基于**同一模型**完成，不得混合多个模型；模型类型不限（World Model、VLA 均可）。
- 32 个任务，每个任务 10 次独立运行；5 类泛化各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
- 单次真机执行上限 **180 s**；排名先看 32 任务总平均成功率，成功率相同看总平均步骤分，再相同看更早提交。
- 评测跨 **N 台机器人**，随机顺序；每台机器人一个固定端口；提交须从 **8765** 起暴露 **N 个连续端口**；N 的确切值由官方另行通知。
- 每端口独立 episode；`reset()` 和历史状态必须隔离；不同端口可能并发调用。
- 另有**不计分的单任务测试通道**，可用于单任务成功率/步骤分验证。

提交 API（2026-10-31 复核）：

- 观测：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640**；双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str`。
- 动作：`joint` 或 `ee` 互斥；EE 动作是**绝对目标位姿**（xyz+rpy，base 系）；`action.pivot [7]`；`action_chunk_size` 固定。
- `action_chunk_size` 是每次 `get_action` 返回的 leading time-axis 长度；index 0 先执行，其余按顺序执行，直到 evaluator 再次调用。**chunk 内没有新观测，也没有打断机制。**
- **没有 depth、camera_info、force/torque、tactile。**
- 评测端逐调用记录延迟、波动和动作统计规律，作为结果可信度的一部分。

**对方案的约束**：FUSE-CAL 必须是每端口独立、CPU 轻量、不抢 GPU 的确定性层；唯一学习模型仍是 WLA。传感器融合不能变成“第二个策略模型”。

### 2.2 数据：33,276 eps / 169.28 h / 94 步；相机参数跨任务变化，腕部内参存在

32 个 HF 数据集合计（2026-10-31 复核）：

| 项 | 数值 |
|---|---:|
| episodes | **33,276** |
| 时长 | **169.28 h**（30 fps） |
| 任务数 | 32 |
| 官方评分步骤总数 | **94** |
| 难度 | Easy 12 / Medium 12 / Hard 8 |
| 单任务 episodes | 969–1,533 |
| 单任务平均时长 | 6.2 s（HangCup）–37.6 s（ToolboxStorage） |

本轮最重要的新事实：**相机参数不是全局常数，腕部也不是“没有内参”。**

抽查 5/32 个数据集（HangCup、FoldTowel、PlugInEthernet、StackBowls、SyringeWaterTransfer）得到：

- 头部双目 `fx` 约 **186.0–282.4 px**，左右目略有差异；基线（`|T_x|`）约 **48.4–61.4 mm**。
- 头部双目 `T` 的 y 分量到 **+8.0 mm**、z 分量到 **-18.9 mm**，尽管 `rectified: true`。这说明“固定内参/外参先验”不够，至少需要每任务/每机器人在线校验。
- 腕部 `color` 有完整内参：`fx` 约 **432.9–436.4 px**，`cx` 约 **316.9–324.3 px**，`cy` 约 **238.7–244.2 px**；不同任务有数像素差异。
- 第 12 轮产物中“腕部相机没有内参矩阵”的说法**作废**；正确的说法是“腕部内参存在，但未被 WLA 训练配置统一使用，且需要在线校验”。

为什么这改变方案：

- 头部 `fx` 跨任务相差约 **52%**，同一物体在图像中的尺度/视差会显著不同；纯 RGB 策略可能学到“任务相机几何”而不是“物体几何”。
- 挑战赛 API 不提供 `camera_info`，测试机器人也不保证与训练数据同一标定；如果不在线自校准，模型只能从像素猜几何。
- 右头相机在 WLA 模型服务器中**没有被使用**（只喂 `cam_left_high` + 左右腕部）。这是一个免费的几何通道：用右头 + 左头做双目，不需要额外硬件。

### 2.3 WLA：6B、30 步、3 路图；右头相机是免费的几何通道

官方 UnifoLM-WLA-1.0（2026-09-28 开源 Base）：

- **6B** 参数，约 **2,500 h** 真机数据，**64** 个任务；支持二指夹爪和五指灵巧手。
- 动作专家默认 `chunk_size=30`、`target_fps=30`，覆盖约 `[0, 29/30]` 秒；默认 4 步扩散去噪。
- 微调冻结 VLM（`qwen_vl_interface`），只训 DiT action head + robot-state projector；默认单张 **24GB** GPU。
- 统一动作 **54 维**、状态 **60 维**；训练动作是相对当前 EE 的 xyz+rotvec。
- 模型服务器只吃三路图：`cam_left_high` + `cam_left_wrist` + `cam_right_wrist`；`cam_right_high` 未使用。
- 服务器返回给客户端的 `action.left_ee_rpy` / `action.right_ee_rpy` 已经是**绝对 xyz+rpy**（服务端把整段 chunk compose 到当前 EE 锚点）；只有绕过服务器直接接 54D 模型时，才需要自己做 compose。
- `action.pivot` 在 WLA server 文档中的顺序是 `vx, vy, vw, yaw, pitch, roll, height`；挑战赛 README 只写“Lower-body / pivot target”，没有逐维定义，必须用单任务通道验证。
- 训练配置有的数据集用 `head_stereo_left_rec`（已校正），有的用 `head_stereo_left`（原始）；挑战赛 `cam_left_high` 对应哪一路、是否已校正，README 没有说明，必须在 G0 核对。

**战略结论**：不要从零训 6B/14B；用官方 WLA Base 做 action-head 微调，把省下的算力投到**观测规范化**和**执行层**。右头相机不是冗余，是 FUSE-GEOM 的第二个几何通道；腕部内参不是缺失，是可以用来做最后厘米级对齐的资产。

### 2.4 榜单：8 个预览模型 + 256 条 runs + “即将发布”，不是正式成绩

2026-10-31 抓取 `leaderboard.html`、`runs.html`、`leaderboard_data.json`：

- 页面显示 8 个预览模型：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。
- `runs.html` 显示 **256 / 256** 条运行记录；页面底部仍有「即将发布 Coming Soon」。
- `leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`。
- 对 8 模型 ×32 任务做 `step_score ~ success_rate` 回归：**R² > 0.999999，最大残差 < 0.006**；每个模型斜率约 **1.31–1.37**。步骤分是脚本生成的线性缩放，不是实测。
- 每任务只有 10 次 trial，但 **232/256** 个任务成功率不是 10% 的整数倍（如 27.29%、27.85%）；真实 10 次 trial 只能是 0/10、1/10、…、10/10。
- 8 个模型的 32 维任务成功率两两相关，**平均 off-diagonal 相关仅 0.098**（min -0.208，max 0.353）。
- 官方难度与预览成功率相关 **-0.232**；Easy 组平均 26.05%、Medium 24.67%、Hard 24.61%，预览成功率并不按官方难度排序。

**结论**：榜单只能当“赛事方预览上限/弱先验”；不能当 SOTA、任务难度表、失败分布。本轮不从预览任务排名挖创新点，只从官方 rubric、API、数据和公开技术路线挖。

### 2.5 官方 rubric：94 步，最后一步权重最高

32 个任务的 `info.json`（2026-10-31 解析）给出 94 个评分步骤：

- 2 步任务 **11** 个：50/50。
- 3 步任务 **14** 个：30/30/40。
- 4 步任务 **5** 个：25/25/25/25。
- 5 步任务 **2** 个：20×5。
- 最后一步权重分别为 **50/40/25/20**；成功是二值，步骤分是部分完成分。

**对策略的含义**：排名成功优先，步骤分只在成功率相同时做 tie-break；因此不能为了步骤分牺牲成功。但最后一步权重高，说明“最后接触/放置”既是成功瓶颈，也是步骤分瓶颈；FUSE-CAL 的几何 + 伪触觉正好打这里。

### 2.6 相关工作：双目/相机条件化/多机评测/榜单审计都已经证明方向，但没人把它组合到本赛题

- **EATR-Stereo**（arXiv 2608.17453）：embodiment-aware token routing，保留主视角 token，用辅助视角构造 CVAT，本体感觉编码器条件化辅助 token；冻结 VLM。公开摘要称 60.0% full-task、100% grasp、80% stage；严重遮挡恢复 80% vs 30%。这是最接近的工作，但它假设有头戴双目且主要解决 token routing，不是“无 camera_info + 多机器人 + 伪触觉”的赛题约束。
- **StereoPolicy**（arXiv 2605.09989）：双目 cross-attention 融合，可适配预训练 VLA；证明双目特征比 RGB-D/点云更稳。
- **StereoVLA**（arXiv 2512.21970）：用大规模合成双目数据训练 GeoSem 编码器，联合深度估计和相机参数估计；真实实验称 33.4% 绝对成功率提升。
- **StereoPatch**（arXiv 2609.15509）：patch-aligned RGB-Depth 融合，强调空间感知。
- **Do You Know Where Your Camera Is?**（arXiv 2510.02268）：用 Plücker ray 显式条件化相机内外参，显著提升 ACT/Diffusion Policy/SmolVLA 的视角泛化；说明“相机几何必须显式进入策略”，不能靠背景捷径。
- **What Are We Actually Benchmarking in Robot Manipulation?**（arXiv 2606.04233）：指出 shortcut solvability、统计显著性缺失、creeping overfitting、data-source dependence 四类 benchmark 失败模式；与本轮“榜单只当弱先验”直接相关。
- **RoboDojo**（arXiv 2607.04434）：42 仿真 + 18 真机任务，统一 sim-and-real 评测与公开榜单，强调可复现评测和部署条件；**ManipulationNet**（arXiv 2603.04363）：真实世界多机评测基础设施，标准化硬件 + 分布式评测。两者支持“多机评测需要协议/指纹/隔离”，但都不是本赛题的单模型 32 任务设置。
- **TacVLA**（arXiv 2603.12665）与 **SimpleTouch**（arXiv 2610.02784）：接触感知 VLA（TacVLA 用触觉门控，SimpleTouch 用触觉专家但免触觉预训练）；但 UniBot API 没有触觉，不能直接搬，只能做伪触觉。
- **Test-Time Compute for Humanoid BFMs**（arXiv 2610.14896）：TTCO 通过采样优化输入命令，不重训，仿真中全局身体位置误差降 79–84%；说明“测试时计算”可以补执行误差，但它是采样优化，不是在线策略更新。
- **Efficient Test-Time Adaptation for Robot Policies**（arXiv 2610.20318）：在线自监督 TTA（TEMPO）；单模型合规和延迟风险高，本轮只参考，不采用。
- **A-SLIP**（arXiv 2604.08528）：声学滑移估计；本赛题无音频，不适用。

**定位**：FUSE-CAL 不是“再做一个双目 VLA”，而是把**双目几何 + 本体感觉 + 每端口标定 + 伪触觉**做成一个确定性观测层，喂给同一个 WLA；它解决的是赛题特有的“无 depth/camera_info/force/tactile + 多机器人 + 单模型”约束。

## 3. 诊断：三个“不一致”让最后 3 厘米变成开环

### 3.1 几何不一致：同一物体在不同任务/机器人上不是同一个尺度

头部 `fx` 186–282、基线 48–61 mm、`T` 的 y/z 分量非零；腕部 `cx` 差 7 px。结果：

- 同一杯子在图像中的像素尺度可能差 50%；
- 同一深度对应的视差差 20% 以上；
- 纯 RGB 策略容易把“相机安装/裁剪/缩放”当成任务线索；
- 测试机器人换一套安装，策略的动作尺度就可能错。

这不是“感知不够语义”，而是**没有米制几何**。

### 3.2 接触不一致：没有力/触觉，但接触状态其实可从本体 + 腕部推断

最后 3 厘米的失败不是“看不懂”，而是“不知道现在是否接触、是否滑移、是否顶住”。API 没有力/触觉，但有：

- 上一条命令的绝对 EE 目标 vs 当前观测 EE 位姿（跟踪残差）；
- 夹爪命令 vs 夹爪实际开度（闭锁残差）；
- 腕部图像中物体 vs 夹爪的相对运动（视觉滑移）；
- 头部双目深度中物体表面 vs 夹爪的距离/法向。

这些量足以做**确定性伪触觉**：自由空间跟踪误差小、接触时跟踪残差大且夹爪闭锁、滑移时物体相对夹爪运动。它不需要第二个学习模型。

### 3.3 评测不一致：榜单是预览噪声，多机是方差来源

- 榜单步骤分是合成的，任务成功率不是 10 次 trial 的整数倍；跨模型任务相关仅 0.098；官方难度与预览成功率负相关。
- 多机评测意味着 N 套相机/夹爪/延迟；如果不做每端口标定，同一模型在不同端口的表现差异会被误读为“模型不鲁棒”。
- 单任务通道只有 10 次/task 时，单任务成功率的标准误约 **13.7pp**；全局 320 trials 的标准误约 **2.4pp**。小样本 A/B 必须配对、bootstrap，不能把 +1–2pp 当结论。

## 4. 方法：FUSE-CAL / FUSE-FLEET

### 4.1 总架构

```text
                    ┌─────────────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1)         │
                    └──────────────┬──────────────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
        ┌──────────────────────────────────────────────────────────┐
        │  Per-port PolicyService (CPU, state isolated)            │
        │  ├─ FLEET-FINGERPRINT: K/T, wrist K, delay, action scale │
        │  ├─ FUSE-GEOM: stereo depth + canonical virtual camera   │
        │  ├─ FUSE-TOUCH: tracking/gripper/wrist contact evidence  │
        │  ├─ CHUNK-SERVO: 30-step plan + 5-step servo             │
        │  └─ FUSE-ADAPTER: canonical obs / geometry token         │
        └──────────────────────────┬───────────────────────────────┘
                                   │ async, batched, per-port session
                                   ▼
                    ┌─────────────────────────────────────────────┐
                    │  Shared WLA server (GPU, single checkpoint) │
                    │  UnifoLM-WLA-1.0, 30-step, 3/4 views        │
                    └─────────────────────────────────────────────┘
```

- **唯一学习模型**：WLA（官方 Base 微调 action head）。
- **确定性层**：标定、双目、规范化、伪触觉、伺服；无学习权重。
- **数据资产**：33k 成功演示 → 相机参数先验、相对目标库、伪触觉阈值校准。
- **每端口隔离**：指纹/标定/plan cache/contact 状态独立；共享只有模型权重。

### 4.2 FUSE-GEOM：在线自校准的米制几何

目标：把四路 RGB + 本体感觉变成 **canonical（规范化）** 的几何观测，让同一个 WLA 在不同任务/机器人上看到同一尺度的世界。

四步：

1. **离线标定库**：解析 32 个数据集的 `camera_params`，建立头部双目 `K/T`、腕部 `K` 的先验分布；记录 `rectified`、`T` 的 y/z 偏移、腕部 `cx/cy` 差异。G0 做全量审计，不只抽查 5 个。
2. **在线头部自校准**：用 `lower_body` 的 waist 3 维 + G1 URDF 恢复头相机在 base 系的近似位姿；用双目极线/桌面平面/夹爪已知几何做鲁棒 refine（Huber/ RANSAC）；输出 `K_head, T_base_head` 及置信度。若 waist 不可用，用“桌面平面 + 已知夹爪宽度”做单目自标定，置信度低时回退先验。
3. **双目深度**：对 `cam_left_high` / `cam_right_high` 做 rectify；SGBM/BM + 亚像素 + 左右一致性 + 中值滤波；输出深度、无效 mask、点云。工作距离 0.3–0.6 m 用头双目；最后 1–2 cm 用腕部。
4. **规范化（canonicalization）**：选一个虚拟头相机 `K0, T0`（固定 fx、principal point、baseline），用深度把左头图像 warp 到虚拟相机；无效深度用边缘填充/原图回退。把 EE 位姿/动作也变换到 canonical base 系。WLA 看到的是“同一个虚拟相机”下的世界；每端口再用逆变换把动作变回去。

输出：

- `canonical_left_high`、`canonical_wrists`（腕部做去畸变 + 统一 resize，不做大角度 warp）；
- `depth_base`、`object/receptacle pose`、`surface normal`、`distance`、`confidence`；
- `T_base_head`、`T_ee_wrist`、`calibration_confidence`。

为什么不是“再训一个深度模型”：

- 透明/反光/变形物体上，学习深度也会失败；赛题只需要局部米制几何，不需要完整 3D 重建。
- 单模型规则下，独立深度网络有合规风险；经典双目 + 置信度门控足够做规范化与接近段。
- 右头相机本来闲置；用它做双目是“免费信息”，不是新增硬件。

### 4.3 FUSE-TOUCH：没有触觉，就用本体 + 腕部做伪触觉

四个证据源：

1. **跟踪残差**：上一条命令的 EE 目标 `x_cmd` vs 当前 `x_obs`；`r_track = ||x_obs - x_cmd||`，以及姿态残差。自由空间小、接触/顶住大。用期望速度归一化，扣除控制器滞后。
2. **夹爪闭锁残差**：命令闭合 vs 实际开度；夹爪停在半闭 → 夹到物体；继续闭合 → 空抓。
3. **腕部视觉滑移**：腕部光流估计物体运动 `v_obj`，本体估计夹爪运动 `v_ee`；夹爪闭合时 `v_obj - v_ee` 大 → 滑移。
4. **深度接近度**：头双目/腕部深度中物体表面到夹爪的距离与法向；接触前减速。

融合：

```text
contact_score = f(r_track, gripper_stall, slip, depth_gap)
```

`f` 用固定权重的证据融合 + 滞回阈值；阈值由离线成功/失败演示校准，不训练学习分类器。输出：

- `contact ∈ {free, contact, slip, unknown}`；
- `contact_confidence`；
- `slip_magnitude`；
- `expected_normal`。

用途：

- 接触段降低法向伺服增益、保留切向修正；
- 滑移触发重抓/降速；
- 自由空间异常接触触发停/重定位（人为干扰恢复）；
- 给 FUSE-ADAPTER 提供接触 token。

**合规**：这是确定性控制器/估计器，不是第二个策略模型；离线阈值校准属于 C1 标注，不改变唯一策略。

### 4.4 FUSE-ADAPTER：把几何/接触证据注入同一个 WLA

三种注入方式，按风险从低到高：

- **A. 图像叠加（默认，零重训）**：把深度边缘、接触热图、标定置信度以低透明度叠加到 `canonical_left_high`；WLA 仍是 3 通道输入。优点是便宜、可回退；风险是可能干扰 VLM 语义。
- **B. 第四路视图（P1）**：把 `canonical_right_high` 作为第四路图，加一个轻量 view-fusion adapter 到 action head；冻结 VLM，只训 adapter + projector。数据里有 `head_stereo_right`，可离线训练；挑战赛 API 也提供右头。需要改模型服务器，但仍是同一个 checkpoint。
- **C. 几何 token（P1）**：把 `object/receptacle pose`、`contact`、`calibration_confidence` 编码成 7–16 维 token，拼接进 robot-state projector；只训 projector/action head。最轻量，但需要改 state 维度。

推荐路线：**A 先过 G1/G3；B/C 只有在 G5 证明增益时才做。** 任何情况下都不外挂第二个策略；所有学习部分都在同一个 WLA checkpoint 内。

### 4.5 FLEET-FINGERPRINT：每端口指纹，让多机评测变成观测优势

每个端口维护一个指纹：

```text
fingerprint = {
  K_head, T_base_head, K_wrist_left/right, T_ee_wrist,
  gripper_delay, gripper_scale, action_scale,
  latency_p50/p99, control_freq_est,
  canonical_K0/T0
}
```

- **冷启动**：用数据集先验 + 第一帧的桌面/夹爪几何做一次快速标定；置信度低时用先验。
- **在线更新**：每 N 帧用重投影误差/跟踪残差更新指纹；漂移大时降增益或回退。
- **持久化**：指纹按端口保存在进程内存/本地文件；`reset()` 清 episode 状态，但不清指纹；不同端口不共享指纹。若评测端要求 `reset()` 全清，则每个 episode 首帧用先验 + 桌面/夹爪几何快速重标定。
- **动作逆变换**：canonical 动作 → 端口 base 系 → API 绝对 EE 位姿；夹爪/ pivot 按端口标定缩放/偏置。
- **共享模型**：N 个轻量 endpoint 转发到共享 WLA；按端口 session 隔离；batch 调度保证 p99。

多机评测的价值不是“跑更多次”，而是**把每台机器人的标定差异显式建模**。如果 FUSE-GEOM 能把这些差异规范化掉，N 台机器人就从方差来源变成“多个标定样本”。

### 4.6 RUBRIC-PORTFOLIO：榜单当弱先验，成功优先

官方排序是字典序：**成功率 > 步骤分 > 更早提交**。所以策略是：

1. **成功优先**：任何工程决策先问“能不能把某个任务的 0 变成 1”，而不是“步骤分能不能 +5”。
2. **榜单只当弱先验**：用 8 个预览模型的成功率给每个任务一个宽区间；不用它排任务难度，不用它选“最难任务”。跨模型相关 0.098，说明任务级排名不可信。
3. **rubric 用于 tie-break**：最后一步权重 50/40/25/20；在成功率接近时，优先投资“最后一步权重高、当前步骤分高”的任务，因为成功后的步骤分更高。
4. **单任务通道做配对 A/B**：选 5 个任务（PlugInEthernet、HangCup、ZipUp、StackBowls、FoldTowel），同初始条件 A/B；每任务至少 10 次，能更多更好；报告配对差值 bootstrap CI。
5. **组合预算**：
   - 70% 工程投接触密集 + 位置/人为干扰轴（FUSE-GEOM + FUSE-TOUCH + CHUNK-SERVO）；
   - 20% 投 WLA adapter / 数据微调（语义/未见物品）；
   - 10% 投语义/变形任务基线（FoldTowel、SpellRobot、ConveyorSorting），防止回归。
6. **提交节奏**：若允许多次提交（需邮件确认），先交安全基线锁“更早提交” tie-break，再交 FUSE-CAL；若只允许一次，先用单任务通道把 FUSE-CAL 打磨到稳定。

## 5. 与第 10–12 轮的关系：保留、升级、剪枝

**保留**：

**升级**：

- 观测层 → 标定层：从“用四路图”升级为“先把四路图标定成同一个虚拟相机”；
- 单机器人 → 多端口：每端口指纹 + 规范化 + 状态隔离；

- 榜单难度表 → 弱先验 + rubric 组合：成功优先，步骤分 tie-break。

**剪枝**：

- 不做独立深度模型（第二个学习模型；透明/反光失败；合规风险）；

- 不做 30Hz 广域网伺服（RTT 不允许；5 步块）；
- 不做逐任务策略（规则禁止；不泛化）；
- 不做力/触觉闭环（API 没有）；
- 不把预览榜单任务排名当难度表（已证伪）；
- 不假设 WLA 已覆盖 32 任务 / `pivot` 语义完全一致（必须单任务通道验证）。

| **G7** | 消融是否支持因果？ | 规范化、伪触觉、指纹、adapter、组合各自 on/off 有可解释差异 | 砍掉无效部分 |
| **G8** | 统计是否支持结论？ | 配对 bootstrap CI；不把 <2.4pp 的全局差异当结论；单任务不把 <13.7pp 当结论 | 增加重复/配对，或只报方向 |

## 7. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定为第二个模型 | 标定/双目/伪触觉/规范化均无学习权重；唯一学习模型是 WLA；FUSE-ADAPTER 在同一 checkpoint 内；提交材料写清 C1/C2/C3 |
| 标定失败 | 规范化错误，动作尺度错 | 置信度门控；低置信回退先验/原图；每端口重投影监控 |
| warp 伪影 | VLM 语义受损 | 保留原图回退；只 warp 头部；腕部只去畸变/resize；G1 消融 |
| 双目透明/反光 | 深度无效 | 无效 mask；腕部 + 伪触觉兜底；不硬做深度 |
| 伪触觉误报 | 错误降增益/停 | 滞回 + 多证据 + 置信度；误报高只做监控 |
| 多端口延迟 | p99 超时 | 共享模型 batch；每端口轻量 endpoint；降分辨率；回退 chunk |
| 榜单过拟合 | 工程投错任务 | 榜单只当弱先验；官方 rubric + 单任务 A/B；不按预览排名选任务 |
| 统计噪声 | +1–2pp 假阳性 | 配对 A/B；bootstrap；320 trials SE≈2.4pp；单任务 10 trials SE≈13.7pp |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |
| 安全 | 碰撞/超调 | 限速/限幅/最大重试；接触/编辑检测即停 |

## 8. 一句话押注

**用右头双目 + 双腕 + 本体感觉做在线自校准的米制几何与伪触觉，用每端口机器人指纹把 N 台机器人规范化到同一个虚拟相机，再让同一个 WLA 在 CHUNK-SERVO 的 5 步闭环里执行；排行榜只当噪声先验，工程按成功优先的官方 rubric 组合投——这就是 FUSE-CAL / FUSE-FLEET。**

# 第 13 轮产物 · FUSE-CAL / FUSE-FLEET 技术报告

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本报告是第 13 轮想法区「FUSE-CAL / FUSE-FLEET」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是给它们加一层“可自校准的观测”。

## 0. 结论与边界

### 0.1 一句话结论

挑战赛的共享瓶颈不只是 1 秒开环 chunk，而是**观测没有统一坐标系**：头部双目内参/外参跨任务变化，腕部内参存在但未统一，多机器人评测又叠加每端口差异；同时 API 没有力/触觉，最后 3 厘米的接触状态不可见。FUSE-CAL 用右头双目 + 双腕 + 本体感觉做**确定性在线自校准与伪触觉**，用每端口指纹做**规范化**，把同一个 WLA 放到同一个虚拟相机下；CHUNK-SERVO 继续做 5 步执行；排行榜只当弱先验，工程按成功优先的官方 rubric 组合投。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| **A** | 官方文档、提交模板、数据集元数据、榜单 JSON 直接核实 | 规则、API、33,276 eps、94 步、WLA `chunk_size=30`、榜单 29.7% |
| **B** | 我们在公开数据/网页上做的分析，可复现 | 相机参数范围、榜单 `step~success` 回归、跨模型任务相关、难度相关 |
| **C** | 设计假设，需 G0–G8 验证 | 规范化 +10pp、伪触觉 precision/recall、多端口方差下降、第四路视图增益 |

### 0.3 新颖性主张（经本轮文献复核，不声称绝对首创）

1. 把**每任务/每机器人的相机参数差异**当作测试时规范化问题，而不是训练时数据增强；用 WLA 闲置的右头相机做双目几何，用每端口指纹把观测映射到同一个虚拟相机。
2. 在没有触觉的 API 下，用**本体跟踪残差 + 夹爪闭锁 + 腕部光流**做确定性伪触觉，不训练第二个接触分类器。
3. 把**多机评测**建模为“每端口指纹 + 共享模型规范化”，并把**排行榜**降级为弱先验，用官方 rubric 做成功优先的组合预算。

### 0.4 本轮不做什么

- 不从零训 VLA/World Model；官方 WLA 已开源 6B Base。
- 不做独立深度模型；用经典双目 + 置信度门控，透明/反光回退。
- 不做学习式接触分类器；伪触觉是确定性证据融合，阈值离线校准。
- 不做完整 32 任务仿真；只做 3 个任务族的标定/压测风洞。
- 不做在线测试时策略更新；TTCO 只作参考，不采用 TTA。
- 不做 30Hz 广域网伺服；用 5 步执行块。
- 不做逐任务策略；规则要求同一模型。
- 不做力/触觉闭环；API 没有。
- 不把预览榜单任务排名当难度表；已证伪。
- 不假设 WLA 已覆盖 32 任务、`pivot` 语义完全一致；必须单任务通道验证。

### 1.1 比赛规则（A）

来源：官方参赛手册（飞书 docx，2026-10-31 经 `r.jina.ai` 复核）、提交模板 README、挑战赛页面。

| 项 | 规则 |
|---|---|
| 模型 | 所有任务须基于**同一模型**完成，不得混合多个模型；模型类型不限 |
| 任务 | 32 项桌面任务 |
| 次数 | 每任务 10 次独立运行 |
| 泛化 | 5 类各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰 |
| 时限 | 单次真机执行上限 **180 s** |

**动作适配修正（重要）**：

- WLA 内部 54D 是相对当前 EE 的 xyz+rotvec。

- 只有**绕过 server 直接接 54D 模型**时，才需要先把整个 30 步 compose 成 base 系绝对目标，再按 5 步切片；否则第 6–30 步会以错误锚点解释。
- 挑战赛观测 EE 是 xyz+rpy（6D），WLA server 期望 `left_ee_6d` / `right_ee_6d` 是 xyz+rot6d（9D）；obs adapter 必须做 rpy→rot6d。

## 2. 问题形式化

### 2.1 评分与统计

总分：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

320 trials 下，若 `p≈0.25`：

```math
\mathrm{SE}(S)\approx \sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

单任务 10 trials 的标准误：

```math
\mathrm{SE}(p_t)\approx \sqrt{\frac{p(1-p)}{10}}\approx 0.137.
```

含义：全局 +2.4pp 才约 1 SE；单任务 +13.7pp 才约 1 SE。单任务通道的 A/B 必须配对、同初始条件、bootstrap；不能把 +1–2pp 当结论。

人为干扰轴：

```math
\Delta S_{\mathrm{human}} = \frac{2}{10}\,\Delta p_h = 0.2\,\Delta p_h.
```

即 human 轴成功率 +10pp → 全局 +2pp。

排名是字典序：

```text
rank_key = (mean_success, mean_step_score, -submission_time)
```

成功优先；步骤分只在成功率相同时 tie-break；更早提交是第三 tie-break。

### 2.2 观测模型与规范化

相机投影：

```math
\tilde{\mathbf u} = K\,[R\,|\,t]\,\tilde{\mathbf X}_{\mathrm{base}},
\qquad
\mathbf X_{\mathrm{cam}} = T_{\mathrm{cam,base}}\,\mathbf X_{\mathrm{base}}.
```

规范化到虚拟相机 `(K0, T0)`：

```math
\mathbf u_0 = \pi\!\left(K_0\,T_{0,\mathrm{base}}\,T_{\mathrm{base},\mathrm{cam}}\,\pi^{-1}(\mathbf u, Z)\right).
```

- `Z` 来自头双目深度；无效深度用原图/边缘回退。
- 头部用完整虚拟相机 warp；腕部只做去畸变 + 统一 resize，避免大角度 warp 破坏接触细节。
- EE 位姿/动作也变换到 canonical base 系；执行前逆变换回端口 base 系。

头部外参：

- 数据里有 `state_d435`（头相机在 base 系 6D）；挑战赛 API 没有 `state_d435`，但有 `lower_body[15]`（左右腿各 6 + waist 3）。
- 用 G1 URDF + waist 3 维恢复头相机近似位姿；用双目极线/桌面平面/夹爪已知宽度 refine。
- 若 waist 不可用，用桌面平面 + 单目自标定；置信度低回退先验。

腕部外参：

- 腕部相机刚性安装在 EE 上；用已知夹爪运动/棋盘格/手眼标定估计 `T_ee_wrist`。
- 数据里没有 `T_ee_wrist`；G0 用腕部图像 + EE 位姿做手眼标定，误差目标 ≤5mm/2°。

深度误差：

```math
\sigma_Z \approx \frac{Z^2}{f\,b}\,\sigma_d.
```

取 `f=250 px`、`b=55 mm`、`σ_d=0.5 px`：

| Z | σ_Z |
|---:|---:|
| 0.3 m | ~3 mm |
| 0.5 m | ~9 mm |
| 1.0 m | ~36 mm |

所以：头双目用于 0.3–0.6m 接近/对齐；最后 1–2cm 用腕部 + 伪触觉。

### 2.3 伪触觉形式化

特征：

```math
r_{\mathrm{track}} = \left\|\mathbf p_{\mathrm{obs}} - \mathbf p_{\mathrm{cmd}}\right\|,
\qquad
r_{\mathrm{rot}} = \left\|\log(R_{\mathrm{obs}}^{-1}R_{\mathrm{cmd}})\right\|,
```

```math
r_{\mathrm{grip}} = \left|g_{\mathrm{cmd}} - g_{\mathrm{obs}}\right|,
\qquad
s_{\mathrm{slip}} = \left\|\mathbf v_{\mathrm{obj}} - \mathbf v_{\mathrm{ee}}\right\|.
```

接触分数：

```math
c_t = \mathrm{sigmoid}\!\left(w_1 \tilde r_{\mathrm{track}} + w_2 \tilde r_{\mathrm{rot}} + w_3 \tilde r_{\mathrm{grip}} + w_4 \tilde s_{\mathrm{slip}} + w_5 \tilde d_{\mathrm{gap}}\right),
```

其中 `~` 表示按自由空间统计归一化；`w` 固定，阈值离线校准；加滞回：

```text
free -> contact: c_t > θ_on for K frames
contact -> free: c_t < θ_off for K frames
slip: s_slip > θ_slip while gripper closed
unknown: calibration_confidence < θ_cal or depth invalid
```

输出 `contact ∈ {free, contact, slip, unknown}`、`contact_confidence`、`slip_magnitude`、`expected_normal`。

用途：

- `contact`：降低法向伺服增益、保留切向修正；
- `slip`：重抓/降速/重规划；
- `free` 中的异常接触：停/重定位（人为干扰恢复）；
- `unknown`：回退 VLA 开环/保守增益。

### 2.4 多端口/多机器人形式化

每端口 `i` 有指纹：

```math
\mathcal F_i = \{K_{\mathrm{head},i}, T_{\mathrm{base,head},i}, K_{\mathrm{wrist},i}, T_{\mathrm{ee,wrist},i}, \tau_i, g_{\mathrm{delay},i}, \alpha_i\}.
```

规范化：

```math
\mathbf o_i^{\mathrm{canon}} = \mathcal C(\mathbf o_i; \mathcal F_i),
\qquad
\mathbf a_i = \mathcal C^{-1}(\mathbf a^{\mathrm{canon}}; \mathcal F_i).
```

- `C` 是确定性变换；`F_i` 由每端口冷启动/在线更新估计。
- 同一个 WLA 只看到 `o_i^canon`；动作逆变换回端口。
- 每端口状态隔离；共享只有模型权重。
- 延迟模型：`T_fb ≈ H_c/f_c + τ_i`；`τ_i` 用 p50/p99 测量；高延迟端口降增益/加 chunk。

### 2.5 竞赛效用

```math
U = \mathrm{lex}\left(
\frac{1}{32}\sum_t p_t,\;
\frac{1}{32}\sum_t s_t,\;
-\text{submission\_time}
\right).
```

任务级工程优先级：

```math
\mathrm{priority}_t = \frac{\Delta p_t}{32\cdot \mathrm{cost}_t},
```

其中 `Δp_t` 是 FUSE-CAL 在该任务的预期成功率增益，`cost_t` 是工程/评测成本。步骤分只在成功接近时用于 tie-break，不作为主目标。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
                    ┌─────────────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1)         │
                    └──────────────┬──────────────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
        ┌──────────────────────────────────────────────────────────┐
        │  Per-port PolicyService (CPU, state isolated)            │
        │  ├─ FLEET-FINGERPRINT: K/T, wrist K, delay, action scale │
        │  ├─ FUSE-GEOM: stereo depth + canonical virtual camera   │
        │  ├─ FUSE-TOUCH: tracking/gripper/wrist contact evidence  │
        │  ├─ CHUNK-SERVO: 30-step plan + 5-step servo             │
        │  └─ FUSE-ADAPTER: canonical obs / geometry token         │
        └──────────────────────────┬───────────────────────────────┘
                                   │ async, batched, per-port session
                                   ▼
                    ┌─────────────────────────────────────────────┐
                    │  Shared WLA server (GPU, single checkpoint) │
                    │  UnifoLM-WLA-1.0, 30-step, 3/4 views        │
                    └─────────────────────────────────────────────┘
```

- 每个端口一个 `PolicyService` 实例；独立 `reset()`、独立 plan cache、独立 goal/contact 状态。
- 标定/双目/伪触觉是 CPU 线程，不阻塞 websocket；WLA 请求异步、可批处理。
- 共享 WLA server 用 session ID 区分端口；模型权重只有一份，不违反单模型。
- GPU 6B bf16 约 12GB；一张 24GB/40GB GPU 可服务多个端口，具体并发取决于 batch/序列长度。

### 3.2 数据流

```text
obs_i
  -> FLEET-FINGERPRINT.estimate/update
  -> FUSE-GEOM.rectify + stereo_depth + canonical_warp
  -> FUSE-TOUCH.features + contact_state
  -> FUSE-ADAPTER.pack(canonical_rgb, depth_edges, contact_token, state)
  -> WLA.predict(30-step plan)
  -> CHUNK-SERVO.correct(plan[t:t+5], contact_state)
  -> FLEET-FINGERPRINT.inverse_transform
  -> API action chunk (5 steps)
```

`metadata` 示例：

### 3.4 动作适配（修正版）

```text
挑战赛 ee 21D:
  left_ee_abs[6], right_ee_abs[6],
  left_gripper[1], right_gripper[1], pivot[7]

WLA 内部 54D:
  left_ee_rel[6], left_gripper[1], left_hand[6],
  right_ee_rel[6], right_gripper[1], right_hand[6],
  waist[3], torso[3], base_vxvy[2], base_wz[1],
  base_pose_rel[6], height[1], left_leg[6], right_leg[6]
```

映射：

1. 若使用官方 action server：`left_ee_abs` / `right_ee_abs` 已是绝对 xyz+rpy，直接取用；gripper 直通；pivot 按 server 的 7 维顺序。
2. 若直接接 54D 模型：先把整个 30 步 chunk compose 到 plan-time 当前 EE 锚点，再切片；`left_ee_abs = compose(T_base_ee_left_current, exp(left_ee_rel))`，转 xyz+rpy；右臂同理。
3. 观测：挑战赛 EE 是 xyz+rpy（6D），WLA server 期望 xyz+rot6d（9D）；obs adapter 做 rpy→rot6d。
4. `pivot`：若语义不确定，先返回全零保持下身体不动；验证后再映射。
5. 手眼/工具坐标：挑战赛 EE 帧与 WLA EE 帧可能差一个 TCP/夹爪长度；用 `example_env.py` + 真实数据校准（平移 ≤1cm、旋转 ≤2°）。

### 3.5 状态机

```text
INIT ──first obs──▶ CALIB ──confidence ok──▶ PLAN ──plan ready──▶ SERVO
  ▲                    │                         ▲                    │
  │                    └─ low confidence ──▶ FALLBACK                │
  │                                                               │
  │                    ┌──────────── contact/slip ────────────────┘
  │                    ▼
  │                 CONTACT ──released──▶ SERVO
  │                    │
  │                    └─ slip ──▶ REGRASP ──▶ SERVO
  │
  └── RECOVER ◀── edit_score > θ_e / unexpected contact
          │
          ├─ target visible ──▶ re-localize ──▶ SERVO
          └─ target lost ──▶ VLA replan ──▶ PLAN
```

- `CALIB`：冷启动标定/指纹；低置信回退先验。
- `SERVO`：正常接近，PBVS 主导，IBVS 辅助。
- `CONTACT`：`contact` 或 `d_t < d_c`；法向降增益，切向保留。
- `REGRASP`：滑移/夹爪闭锁异常；重抓。
- `RECOVER`：人为干扰/编辑检测；停 → 重定位 → 更新 goal 或重规划。
- `DONE`：成功/最大步数；清 episode 状态，保留指纹。

### 3.6 失败处理

- 任何异常 → 返回上一组合法 chunk 或安全 hold；绝不返回 NaN/错误形状。
- 标定置信度低 → 原图 + 先验 + 保守增益。
- 深度无效 → 腕部 2D + 伪触觉 + VLA 开环。
- 伪触觉误报 → 只监控，不参与控制。
- 多端口超时 → 降分辨率/加 chunk/回退基线。
- 每端口 `reset()`：清 plan cache、goal、contact、episode 计数；保留 fingerprint。

## 4. 创新点清单

### 4.1 FUSE-GEOM（P0）：在线自校准的米制几何

**动机**：头部 `fx` 跨任务 186–282、基线 48–61mm、`T` 的 y/z 非零；API 无 camera_info；多机器人每端口不同。纯 RGB 策略容易把相机几何当任务线索。

**做法**：

- 离线：32 数据集 `camera_params` 标定库；头双目 `K/T`、腕部 `K`、`state_d435`、rectified 标志。
- 在线：waist + URDF 恢复头相机位姿；双目极线/桌面平面/夹爪几何 refine；输出置信度。
- 双目：SGBM/BM + 亚像素 + 左右一致性 + 中值；输出深度/无效 mask/点云。
- 规范化：虚拟头相机 `K0/T0`；深度 warp 左头；腕部去畸变/resize；EE/动作 canonical 变换。
- 输出：canonical 图像、`depth_base`、object/receptacle pose、surface normal、distance、confidence。

**差异**：不是“再训深度模型”，而是确定性标定 + 规范化；不是只用左头，而是把 WLA 闲置的右头变成双目几何通道。

**可行性**：数据有双目/腕部内参/EE 位姿；CPU 可实现；WLA 不改结构即可吃 canonical 图像。

**资源**：1 名感知/标定工程师；CPU 8 核；无额外 GPU。

**风险**：透明/反光深度失败；warp 伪影；waist→头相机运动学不准；腕部手眼标定误差。

**实验门**：G0/G1；重投影 ≤3px，深度 ≤10mm@0.3–0.6m，canonical action error 降 ≥15%。

**来源**：数据集 `meta/info.json`；`Do You Know Where Your Camera Is?`；StereoPolicy/StereoVLA。

### 4.2 FUSE-TOUCH（P0）：没有触觉，就用本体 + 腕部做伪触觉

**动机**：API 无 force/tactile；最后 3 厘米的接触/滑移/顶住不可见；开环 chunk 让接触事件发生在 chunk 内部。

**做法**：

- 跟踪残差：上一条命令 EE 目标 vs 当前观测 EE 位姿；归一化 + 扣除滞后。
- 夹爪闭锁：命令闭合 vs 实际开度；半闭=夹到，继续闭合=空抓。
- 腕部滑移：物体光流 vs 夹爪运动；闭合时相对运动=滑移。
- 深度接近度：物体表面到夹爪距离/法向。
- 确定性融合 + 滞回；阈值离线校准；输出 contact/slip/unknown + confidence。
- 接到 CHUNK-SERVO：接触段降法向增益、滑移重抓、异常接触停/重定位。

**差异**：不训练第二个接触分类器；用物理可解释的残差；符合单模型规则。

**可行性**：API 有 EE 位姿/夹爪/腕部图；数据有成功/失败演示可校准阈值；CPU 轻量。

**资源**：1 名控制工程师；CPU；无需额外传感器。

**风险**：跟踪残差受控制器滞后/饱和干扰；夹爪闭锁阈值随物体变化；滑移光流在纹理弱时失败。

**实验门**：G2；precision/recall ≥0.8，自由空间误报 <10%，延迟 ≤1 个执行块。

**来源**：TacVLA/SimpleTouch（接触密集）；GEO-RESIDUAL（残差）；CHUNK-SERVO（执行层）。

### 4.3 FUSE-ADAPTER（P1）：把几何/接触证据注入同一个 WLA

**动机**：WLA 只吃 3 路图；右头/深度/接触证据没有入口；但单模型规则不允许外挂第二个策略。

**做法（按风险从低到高）**：

- **A. 图像叠加（默认，零重训）**：深度边缘/接触热图/置信度低透明度叠加到 `canonical_left_high`；WLA 仍是 3 通道。
- **B. 第四路视图**：`canonical_right_high` 作为第四路；加轻量 view-fusion adapter 到 action head；冻结 VLM，只训 adapter + projector；数据有 `head_stereo_right`。
- **C. 几何 token**：object/receptacle pose、contact、calibration_confidence 编码成 7–16 维 token，拼接进 robot-state projector；只训 projector/action head。

**差异**：所有学习部分都在同一个 WLA checkpoint 内；不是外挂第二个模型。

**可行性**：A 立刻可做；B/C 需要改模型服务器/输入维度，但有 24GB 微调条件。

**资源**：1 名 WLA 工程师；1×24GB GPU；数据有双目/EE 位姿。

**风险**：A 可能干扰 VLM；B/C 可能回归；第四路视图与训练分布不一致。

**实验门**：G5；相对 3 视图 action error/成功率提升且无回归；否则保留 A。

**来源**：EATR-Stereo（辅助视角 token routing）；StereoPolicy/StereoVLA；WLA 训练配置。

### 4.4 FLEET-FINGERPRINT（P1）：每端口指纹，让多机评测变成观测优势

**动机**：N 台机器人/N 个端口；每端口相机/夹爪/延迟可能不同；同一模型在不同端口表现差异会被误读为不鲁棒。

**做法**：

- 每端口指纹：`K_head, T_base_head, K_wrist, T_ee_wrist, gripper_delay, action_scale, latency_p50/p99, control_freq_est`。
- 冷启动：数据集先验 + 第一帧桌面/夹爪几何快速标定；低置信回退先验。
- 在线更新：每 N 帧用重投影/跟踪残差更新；漂移大降增益/回退。
- 持久化：按端口保存；`reset()` 清 episode 状态，不清指纹；不同端口不共享。若评测端要求 `reset()` 全清，则每个 episode 首帧用先验 + 桌面/夹爪几何快速重标定。
- 动作逆变换：canonical → 端口 base → API 绝对 EE；夹爪/pivot 按端口缩放/偏置。
- 共享模型：N 个轻量 endpoint → 共享 WLA；session 隔离；batch 调度保 p99。

**差异**：不是 N 份模型，而是 N 份指纹 + 一个模型；把多机差异显式建模。

**可行性**：提交模板明确支持“共享一个模型 + N 个 endpoint”；每端口独立 reset；CPU 可做。

**资源**：1 名后端/评测工程师；CPU；共享 GPU。

**风险**：标定漂移；端口间并发；指纹估计耗时；N 未知。

**实验门**：G4；N=2–4 无状态泄漏，p99 ≤150ms，跨端口方差下降。

**来源**：提交 README（N ports/隔离/共享模型）；ManipulationNet/RoboDojo（多机评测协议）。

### 4.5 RUBRIC-PORTFOLIO（P1）：榜单当弱先验，成功优先

**动机**：榜单步骤分合成、任务成功率非 10% 整数倍、跨模型相关 0.098、官方难度与预览成功率 -0.232；按榜单排名分配工程会 overfit。

**做法**：

- 成功优先：`priority_t = Δp_t/(32·cost_t)`；步骤分只 tie-break。
- 榜单只给宽先验；不用任务排名选“最难任务”。
- 官方 rubric：最后一步权重 50/40/25/20；成功后的步骤分更高。
- 单任务通道：5 任务配对 A/B；同初始条件；10+ trials；bootstrap。
- 组合预算：70% 接触密集 + 位置/人为干扰；20% WLA adapter/数据微调；10% 语义/变形基线防回归。
- 提交节奏：多次提交先交安全基线锁“更早提交”，再一次 FUSE-CAL；只一次则先单任务打磨。

**差异**：把“排行榜”从难度表降级为弱先验；把官方 rubric 变成工程预算。

**可行性**：无需额外模型；只需评测协议/统计。

**资源**：1 名评测/策略；单任务通道。

**风险**：单任务 10 trials 噪声大；多次提交未确认；预览榜单误导。

**实验门**：G3/G8；配对 A/B + bootstrap；不把 <2.4pp 全局/<13.7pp 单任务当结论。

**来源**：官方手册/rubric；榜单 JSON；benchmark 审计论文。

### 4.6 FLEET-TWIN（P2）：多机器人标定/压测风洞

**动机**：多端口/多相机/延迟差异难以在真机上穷举；需要可重复的压力测试。

**做法**：

- MuJoCo/IsaacLab 轻量场景：peg-in-hole、hang/stack、zip/unlock 三个任务族。
- 采样 5 个数据集的相机参数范围（fx 186–282、baseline 48–61mm、T y/z）；腕部内参；延迟 0–150ms；夹爪延迟；图像噪声。
- N=2–4 端口；每端口不同指纹；测试标定/规范化/伪触觉/调度。
- 只做控制器风洞，不训策略；sim 成功率不作为真机预测。

**差异**：不是完整 32 任务仿真；只压测 FUSE-CAL 的标定/延迟/多端口。

**可行性**：官方有 IsaacLab/MuJoCo 仓库；3 个任务族可控。

**资源**：1 名仿真工程师；CPU/GPU；2–3 周。

**风险**：sim gap；接触模型不准；场景搭建成本。

**实验门**：G4；标定/延迟/多端口稳定域；不用于策略训练。

**来源**：官方仿真仓库；RoboDojo/MagicSim（评测基础设施）。

### 4.7 优先级与剪枝

| 优先级 | 做什么 | 为什么 | 不做什么 |
|---|---|---|---|
| **P0** | FUSE-GEOM + FUSE-TOUCH + CHUNK-SERVO 集成 | 直接打几何/接触瓶颈；可离线/单任务验证 | 独立深度模型、学习式接触分类器 |
| **P1** | FUSE-ADAPTER（A 先，B/C 后）+ FLEET-FINGERPRINT | 把证据注入同一 WLA；多机规范化 | 第二个策略模型、N 份模型 |
| **P1** | RUBRIC-PORTFOLIO | 防止榜单 overfit；成功优先 | 按预览排名选任务、追步骤分 |
| **P2** | FLEET-TWIN | 多机/延迟压测 | 完整 32 任务仿真、sim-to-real 策略训练 |

**明确剪枝**：从零训 VLA/World Model、独立深度网络、学习式接触分类器、完整 32 任务仿真、测试时梯度更新、30Hz 广域网伺服、逐任务策略、力/触觉闭环（API 没有）、6D 物体位姿网络（透明/变形不可靠）、把预览榜单当难度表。

## 5. 实验设计与门

### 5.1 实验矩阵

| 阶段 | 数据/环境 | 目的 | 主要指标 |
|---|---|---|---|
| 离线回放 | 32 数据集 `meta/info.json` + 演示 | 相机参数审计、标定、canonicalization、伪触觉阈值 | 重投影、深度误差、contact precision/recall |
| 仿真风洞 | FLEET-TWIN 3 任务族 + N 端口 | 标定/延迟/多端口/规范化消融 | 成功率、p99、跨端口方差 |
| 真机单任务 | 不计分单任务通道 | FUSE-CAL vs CHUNK-SERVO 配对 A/B | 成功率、步骤分、耗时、p99 |
| 全量干跑 | 32 任务 ×10 | 稳定性/内存/端口隔离 | 无崩溃、超时、内存 |
| 正式提交 | 32 任务 ×10 | 最终排名 | 平均成功率、步骤分、提交时间 |

### 5.2 门 G0–G8

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| **G0** | 32 数据集相机参数/腕部内参/rectified 是否可审计？ | 32/32 解析成功；头双目/腕部 K 完整；重投影 ≤3px；深度 ≤10mm@0.3–0.6m 刚体 | 只用头双目先验；腕部只做 2D 粗对齐 |
| **G1** | 规范化是否真的让几何一致？ | 合成相机扰动下 action error 降 ≥15%；位姿误差 ≤5mm/2°；原条件不回归 | 放弃 warp，只保留几何 token/深度 |
| **G2** | 伪触觉是否可信？ | 接触/滑移 precision/recall ≥0.8；自由空间误报 <10%；延迟 ≤1 个执行块 | 只做监控，不参与控制 |
| **G3** | 真机单任务是否涨点？ | 5 任务中 ≥3 个 +10pp；FoldTowel 不回归 >5pp；p99 ≤150ms | 不提交 FUSE-CAL；回退 CHUNK-SERVO |
| **G4** | 多端口是否隔离/稳定？ | N=2–4 无状态泄漏；reset 干净；p99 ≤150ms；跨端口方差下降 | 减 N/共享 batch/回退单端口 |
| **G5** | 第四路视图/几何 token 是否有增益？ | 相对 3 视图 action error/成功率提升；无回归 | 保留 A 方案（图像叠加） |
| **G6** | 32 任务干跑是否稳定？ | 320 trials 无崩溃；内存不涨；超时可控 | 回退基线 |
| **G7** | 消融是否支持因果？ | 规范化、伪触觉、指纹、adapter、组合各自 on/off 有可解释差异 | 砍掉无效部分 |
| **G8** | 统计是否支持结论？ | 配对 bootstrap CI；不把 <2.4pp 全局/<13.7pp 单任务当结论 | 增加重复/配对，或只报方向 |

所有门先在离线回放和单任务不计分通道上过；没有过门，不烧正式提交。

### 5.3 消融

| 消融 | 对比 | 预期（假设，需验证） |
|---|---|---|
| canonicalization | raw vs canonical | 相机扰动下 action error 降；原条件不回归 |
| stereo depth | 无深度 vs 头双目 | 接近段位姿误差降；透明物体回退 |
| pseudo-tactile | 无 contact vs contact-gated servo | 接触任务成功率升；自由空间不降 |
| per-port fingerprint | 全局标定 vs 每端口 | 跨端口方差降；p99 稳定 |
| adapter | 3 视图 vs 4 视图/几何 token | 动作误差/成功率升；无回归 |
| portfolio | 榜单排名 vs rubric/成功优先 | 工程投到更高边际任务；不 overfit |

### 5.4 统计协议

- 全局 320 trials，`SE≈2.4pp`；单任务 10 trials，`SE≈13.7pp`。
- 单任务 A/B：同初始条件、交替 A/B、配对差值、bootstrap 95% CI。
- 全量：报告每任务 `p_t`、总平均、步骤分、p50/p99 延迟、超时率。
- 不把“预览榜单 +X%”当结果；不把单任务 +1–2pp 当结论。
- 数据划分：按 session/物体/背景分组；相邻帧不跨 split。

## 6. 竞赛策略

### 6.1 任务组合（先验，待单任务通道更新）

| 档 | 任务 | 为什么 | 投什么 |
|---|---|---|---|
| **A. 接触密集（19）** | HangCup、DisconnectEthernet、ToolboxStorage、PlugCharger、Unlock、ArrangeTestTubes、PourOutMedicine、OrganizeStationery、PackBag、ZipUp、PaperCupStacking、StorePaddle、StoreCups、PlugInEthernet、StackBowls、StoreEarphones、PackPhone、OrganizePencilCase、SyringeWaterTransfer | 最后一步需要毫米级插入/挂/叠/拉链/锁/拧 | FUSE-GEOM + FUSE-TOUCH + CHUNK-SERVO |
| **B. 语义/变形/动态（13）** | FruitCollection、PackDoll、FruitSorting、ColorArrangement、PlacePhotoFrame、OrganizeBookshelf、PickOutBatteries、OrganizeTools、FoldTowel、ArrangePlates、SpellRobot、ConveyorSorting、RemovePinnedNote | 语义/外观/变形/动态为主 | WLA 数据微调 + adapter；FUSE-CAL 只做轻量几何 |
| **C. 观察/低投入** | 单任务通道里 `p_t` 接近 0 且失败在早期感知/抓取的任务 | 伺服杠杆低 | 保留基线，不烧工程 |

这张表是**先验**，不是结论。单任务通道测完后，用 `Δp_t/cost_t` 重排；每测 3–5 个任务更新一次。

### 6.2 单任务通道协议

1. 选 5 个代表任务：PlugInEthernet（插入）、HangCup（挂）、ZipUp（拉链）、StackBowls（叠）、FoldTowel（变形，防回归）。
2. 每个任务至少 10 次 A/B：FUSE-CAL off/on；同初始条件；交替；记录成功、步骤分、耗时、p99。
3. 通过标准：至少 3 个任务 +10pp；FoldTowel 不回归 >5pp；p99 ≤150ms。
4. 再扫 `H_c ∈ {3,5,8}`、`image_resize` 两档、canonicalization on/off；选 p99 与成功率的最佳折中。
5. 最后才跑 32×10 正式评测。

### 6.3 提交节奏

- 若允许多次提交（需邮件确认）：先交**安全基线**（官方 WLA + chunk 30 + 官方 API 适配），锁“更早提交” tie-break；再交 FUSE-CAL。
- 若只允许一次：先用单任务通道把 FUSE-CAL 打磨到稳定，再交最终版。
- 不要把 320 trials 浪费在“从零训 6B”“完整世界模型”“32 个任务各训一个策略”上；这些边际收益低。

### 6.4 预期增益算术（假设，不是结果）

- 若 10 个接触任务各 +10pp：全局 `10/32×10=+3.1pp`。
- 若 15 个任务各 +10pp：全局 `15/32×10=+4.7pp`。
- 若 human 轴 +10pp：全局 `0.2×10=+2pp`。
- 若步骤分 tie-break：成功后的最后一步权重 50/40/25/20，接触任务成功后步骤分更高。

这些是预算算术，不是承诺；必须用 G3/G8 验证。

### 6.5 榜单怎么用

- **只用**：给每个任务一个宽成功率先验；识别“预览特别低”的任务做额外数据/单任务测试。
- **不用**：任务难度排名、步骤分预测、失败分布、SOTA 对比。
- **理由**：步骤分合成、成功率非 10% 整数倍、跨模型相关 0.098、官方难度与预览成功率 -0.232。

## 8. 风险与合规

### 8.1 单模型合规的三种模式

| 模式 | 含义 | 本方案 |
|---|---|---|
| **C1 离线标注** | 用离线数据生成标签/阈值，不改变在线策略 | 相机先验、伪触觉阈值、演示目标库 |
| **C2 确定性控制器** | 无学习权重的控制/估计 | 标定、双目、规范化、伪触觉、伺服 |
| **C3 同 checkpoint 特征** | 用同一个 WLA 的特征/头 | FUSE-ADAPTER A/B/C 都在同一 checkpoint 内 |

**红线**：不加载第二个学习策略/残差网络/独立视觉编码器；不把独立深度模型/接触分类器放在在线路径。若离线用了学习模型，只用于标注，并在提交材料中声明。

### 8.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定为第二个模型 | C1/C2/C3；提交材料写清；在线只跑 WLA |
| 标定失败 | 规范化错误，动作尺度错 | 置信度门控；低置信回退先验/原图；每端口重投影监控 |
| warp 伪影 | VLM 语义受损 | 保留原图回退；只 warp 头部；腕部只去畸变/resize；G1 消融 |
| 双目透明/反光 | 深度无效 | 无效 mask；腕部 + 伪触觉兜底；不硬做深度 |
| 伪触觉误报 | 错误降增益/停 | 滞回 + 多证据 + 置信度；误报高只做监控 |
| 多端口延迟 | p99 超时 | 共享模型 batch；每端口轻量 endpoint；降分辨率；回退 chunk |
| reset 语义 | 指纹被清/状态泄漏 | 先确认评测端 reset 语义；若全清则每 episode 首帧重标定；指纹不跨端口共享 |
| 榜单过拟合 | 工程投错任务 | 榜单只当弱先验；官方 rubric + 单任务 A/B；不按预览排名选任务 |
| 统计噪声 | +1–2pp 假阳性 | 配对 A/B；bootstrap；320 trials SE≈2.4pp；单任务 10 trials SE≈13.7pp |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |
| 安全 | 碰撞/超调 | 限速/限幅/最大重试；接触/编辑检测即停 |
| 语言映射 | WLA 不响应挑战赛指令 | 32 任务语言 → WLA `unnorm_key`/prompt 映射；单任务通道验证 |
| 右头不同步 | 双目深度错 | 时间戳/极线检查；不同步则只用左头 + 腕部 |
