# 第 3 轮迭代（灵感循环 v3：「少样本学习」×「多机协同」）—— 把泛化拆成「检索式少样本」与「评测机群协同」

> 承接 v2（UIP-01′~15）。本轮不换题，而是回答 v2 没回答的两个问题：① 公开数据每任务约千条，为什么仍会「泛化不足」？因为缺的不是训练样本，而是**测试偏移轴上的支持样本**——`unseen_object_*` 在定义上不可能有演示，`human_*` 的「反向撤回」在公开数据里为 0；② 「多机协同」在本题里不是两台机器人一起做同一个桌面任务（赛题是单机单 episode），而是**评测机群**：N 台真机、N 个端口、随机顺序、并发调用。把这两点读准，v3 的新增点自然落在 **检索式少样本（UIP-16）** 与 **机群协同服务（UIP-17/18）** 上。

> v2 已核实且本轮继续沿用的事实（32 任务计分点、`generalization.human_*` 的「反向撤回」、开环动作块、JPEG q95、Gazebo/Isaac 资源等）见 v2 §0，检索日期 2026-11-12。

**由新事实直接推出的两个判断**：

1. 每任务约千条演示 ⇒ **不是 few-shot 数据稀缺**；真正的稀缺是**偏移轴上的支持样本**。所以「少样本学习」应理解为「用少量支持样本做测试时条件化（in-context conditioning）」，而不是「用少量演示训练」。
2. 评测是 N 端口并发 ⇒ **「多机协同」是服务侧协同**（共享骨干、共享检索索引、统一调度、严格状态隔离），不是机器人物理协作。把它读成后者，会做出赛题里根本不存在的方案。

## 1. v2 清单诊断（v3 的取舍）

- **保留旗舰**：UIP-01′（RHPV-D）仍是最高杠杆，因为 `human_*` 的「反向撤回」是规则级事实。
- **升级**：UIP-08′（LAT-ENG）→ **UIP-17 FCS**，把「多端口」从工程细节提升为**机群级调度与隔离协议**；UIP-13（ACS）、UIP-15（CSG）并入 FCS 的延迟预算。
- **新增**：UIP-16 FSRA（检索式少样本适配）、UIP-17 FCS（机群协同服务）、UIP-18 FEX（机群实验台）。三者正好把两个灵感词变成可落地的东西。
- **修剪**：不再新增「外部 VLM 验证器」；FSRA 的检索编码器必须来自主骨干或经典几何/颜色特征，避免「单模型」合规争议。UIP-04/10 继续封存。
- **不变**：GSO/DRF（UIP-11/12）仍是离线判分与造数据的两条腿；v3 让它们为 FSRA 提供**支持集**与**恢复片段**。

## 2. 灵感词一：少样本学习（直觉 → 严谨定义）

**直觉**：你有一千条「正常演示」，但测试时出现的是没见过的物品、被挪动的位置、被人工撤回的进度。此时再「多训一点」没用——你缺的是**关于当前这个新场景的几条支持样本**。人做新任务时也是看两眼示范就会，而不是重训大脑。所以少样本学习的落点是：**在推理时，用少量检索到的支持片段把策略条件化到当前 episode**。

**严谨定义**：设公开数据 `D_pub`、合成数据 `D_syn`（UIP-12），语言指令 `l`，episode 前 `k` 帧观测 `o_{0:k}`。定义检索器 `R_φ`，支持集

`S_e = R_φ(D_pub ∪ D_syn, q(o_{0:k}, l), m)`，`|S_e| = m ≤ 8`。

策略为 `π_θ(a_t | o_t, l, S_e)`，其中 `S_e` 在一次 `reset()` 时检索一次（必要时每 `K` 步刷新）。训练用 **episodic meta-objective**：按「留出物品/背景/位置」构造 episode，支持集来自其余 episode，损失为行为克隆 + 支持集相关性判别 + 检索对比损失。推理期**不做梯度更新**（接口也不允许），因此「few-shot」= **in-context conditioning on m support segments**，不是 fine-tune。

偏移轴上的「支持样本数」记为 `s_axis`：公开数据里 `s_human = 0`、`s_unseen = 0`，这正是要补的洞。

**为什么它能同时打 unseen_object 与 human_* 撤回**：

- **未见物品**：支持集提供「同类可供性」的先验（怎么抓、放哪、什么姿态），当前帧负责把新物品 grounding 到先验上；支持集是**先验**，不是模板。
- **人为撤回**：检测到 `regressed` 后，从 `D_syn` 检索 `(撤回前 → 撤回 → 恢复)` 片段，作为「恢复支持集」条件化，直接复用示范者的恢复动作，而不是从零试错。

## 3. 灵感词二：多机协同（直觉 → 严谨定义）

**直觉**：赛题里的「多机」是**评测机群**：N 台机器人、N 个端口、随机顺序、可能同时调用。你要做的不是让两台机器人商量，而是让**一套模型服务好 N 个互不相干的 episode**：共享该共享的（权重、检索索引、校准统计），隔离必须隔离的（观测、历史、KV、reset 状态），并把延迟波动压住。

**严谨定义**：机群服务器 `F = (θ, M, Sched)`，端口 `p = 1..N`。每个端口有私有 episode 状态 `h_p`；共享只读资源为模型权重 `θ`、公开/合成检索索引 `M`、离线校准统计 `C`。**隔离不变量**：`∀p≠q`，端口 `p` 的观测、动作、历史、KV、reset 计数对 `q` 不可见。调度器为每个请求分配预算 `B_p`，采用**截止时间感知批处理**（deadline-aware batching）。定义**机群延迟膨胀**

`Δ = max_p L_p − median_p L_p`，目标 `Δ ≤ ε`，且 `p99(L_p) ≤ B`。

另定义**可共享/不可共享清单**（机群记忆契约）：可共享 = 权重、公开检索索引、全局归一化统计、离线校准；不可共享 = 原始观测、动作、episode 历史、每端口 KV、reset 状态、在线学到的样本。

**为什么这不是「多模型」**：所有端口共享同一 `θ`；检索索引是数据不是模型；调度器是工程组件。单模型合规不被破坏。

## 4. 瓶颈假设（v3）

- **H1（最高杠杆）**：偏移轴支持样本为 0 ⇒ 检索式条件化 + 合成恢复片段，是唯一能在不重训的前提下补洞的路径。
- **H2**：N 端口并发下，**延迟方差**会直接进可信度口径；批处理若不做截止时间控制，会把「省显存」换成「p99 爆炸」。
- **H3**：数据键 ≫ 接口键 ⇒ 在 `state_torso/d435/base_command` 上训练的模型会出现**状态捷径**；测试时这些键不存在，性能骤降。必须做接口对齐的输入裁剪与鲁棒训练。
- **H4**：跨端口只能共享参数/统计，不能共享原始 episode；否则既违反状态隔离，也会把 A 机器人的偶然误差传染给 B。
- **H5**：检索到的「视觉相似」不等于「因果相关」；支持集若不加相关性门控，会把公开数据的虚假相关放大。

## 6. 本轮最值得押注

**→ 押注：UIP-16 FSRA × UIP-01″ RHPV-D+ × UIP-17 FCS**——用检索支持集补「偏移轴零样本」，用滚动验证-重做兜住 `human_*` 撤回，用机群调度与隔离保证 N 端口下的可信度。三者都落在选手 API 权限与离线算力之内，且不引入第二个模型。

**一句话最大风险**：把「检索相似」误当成「任务相关」，会让 FSRA 在公开分布上越拟越像、在真正的偏移轴上仍然失效；同时机群批处理若压不住 p99，会把省下的显存换成可信度扣分。

## 1. 旗舰深潜：UIP-01″ · RHPV-D+（Retrieval-conditioned Rolling-Horizon Progress-Verified with Disturbance-awareness）

- **机制**：动作块 `A=(a_1..a_{T_a})` 不整段盲执行。每 `k` 步用**进度验证器** `V(o_t,l,g,S_e)` 判断当前子目标 `g` 的状态 ∈ {`done`,`ongoing`,`fail`,`regressed`}。`regressed` 由时序差分（子目标从 done 回退到 undone）或视觉/几何判据触发；一旦确认，**不前进**，而是切换到**恢复支持集** `S_rec`（来自 UIP-12 的「撤回前→撤回→恢复」三元组）重做该子目标。
- **与 v2 的差异**：
  1. v2 的验证器只看当前观测；v3 把 `S_e`（UIP-16 检索到的支持片段）作为条件，用「同类任务的完成态长什么样」来校准 `done/regressed`，显著降低单帧误判。
  2. v2 的「重做」是从当前状态重新采样；v3 的「重做」先用 `S_rec` 条件化，直接模仿示范者的恢复动作。
  3. v2 的块长只按阶段选；v3 的块长同时受 UIP-17 的**端口截止时间**约束：机群忙时回退到短块/单步快路径，避免排队。
- **可行性**：高。`action_chunk_size`、`reset()`、`get_action` 均在接口内；验证器优先用**几何+语言规则**（零额外模型），需要学习时从主骨干蒸馏小头；支持集检索用主骨干编码器或经典特征。
- **资源**：公开 32 数据集（写判据+弱标注）；1 张推理卡；无额外接口；离线 GSO 回放调参。
- **落地**：① 逐任务写 2–5 个可观测子目标（与计分点对齐，见 §6）；② 写 `done/fail/regressed` 判据；③ 建支持集检索索引（§2）；④ 在 loop 内接入 k 步验证与状态机；⑤ 用 UIP-11 离线回放调参；⑥ 用 UIP-17 压测 N 端口延迟；⑦ 真机校准。
- **风险**：误判 `regressed` 会「反复重做」；用 UIP-15′ 三重护栏（置信度门限 / 最大重做次数 / 延迟预算）兜底。

```python
class RHPVDPlus:                         # UIP-01″ + UIP-13′ + UIP-15′
    def __init__(self, policy, verifier, retriever, scheduler,
                 K_MAX=8, conf_thr=0.6, max_redo=2, budget_ms=200):
        self.policy, self.verifier, self.retriever = policy, verifier, retriever
        self.sched = scheduler
        self.K_MAX, self.conf_thr, self.max_redo, self.budget_ms = K_MAX, conf_thr, max_redo, budget_ms

    def reset(self):
        self.policy.reset(); self.g = 0; self.redo = 0; self.buf = []

    def get_action(self, obs):
        st, p = self.verifier(obs, self.policy.lang, self.g, self.policy.S)
        if p >= self.conf_thr and st == "regressed" and self.redo < self.max_redo:
            # 用「撤回前→撤回→恢复」支持集条件化，再重做同一子目标
            self.policy.S = self.retriever.recovery(self.policy.lang, obs, self.g)
            self.redo += 1; self.buf = []
        elif p >= self.conf_thr and st == "done":
            self.g += 1; self.redo = 0
        if not self.buf:
            k = self._pick_k(obs)                 # 阶段 × 机群负载
            self.buf = list(self.policy.get_action(obs, k))[:k]
        return self.buf.pop(0)

    def _pick_k(self, obs):
        if self.sched.is_congested():             # 机群 p99 逼近预算
            return 1                              # 单步快路径
        return min(self.K_MAX, self.policy.phase_k(obs, self.g))
```

## 2. UIP-16 · FSRA（Few-Shot Retrieval Adapter）

### 2.1 支持集记忆的模式

每条记忆项存：`task_id`、`language`、物体属性（类别/颜色/尺寸/可供性）、初始位姿、动作片段、结果标签（成功/失败/恢复）、可选的恢复三元组。检索键由三部分拼接：

`q = [E_img(o_{0:k}), E_lang(l), E_geo(s_0)]`

其中 `E_img/E_lang` 来自**主骨干自己的编码器**（避免外部 VLM 合规风险）；若主骨干无合适编码器，则用经典特征（颜色直方图 + 前景掩码几何 + 夹爪位姿）作冷启动。检索用余弦相似度，先按 `task_id`/技能图节点做硬门控，再在门内 top-m。

### 2.2 Episodic meta-training（学会「怎么用支持集」）

- 以「留出物品实例 / 背景 / 位置」构造 episode：当前 episode 的支持集只从**其余** episode 中检索，强制模型学会从少量支持片段迁移，而不是背当前轨迹。
- `m ∈ {2,4,8}` 随机采样，训练支持集大小鲁棒性；推理时按延迟预算选 `m`。
- 损失：`L = L_BC + λ1 L_rel + λ2 L_contrast`。`L_rel` 训练「支持片段相关性头」，把视觉相似但因果无关的片段降权；`L_contrast` 拉近「同可供性/同子目标」的查询-支持对。
- **不做**在线梯度更新：接口没有训练钩子，且会引入状态共享与可信度风险。

### 2.3 推理期流程

1. `reset()` 后用前 `k` 帧 + 语言检索一次 `S_e`（`m` 条，按延迟预算裁剪）。
2. 策略解码时对 `S_e` 做 cross-attention；若验证器连续低置信，或检测到 `regressed`，刷新/替换为恢复支持集 `S_rec`。
3. 支持集只读、不可写；不把当前 episode 的原始观测写回共享索引（避免跨 episode 泄漏）。

### 2.4 与两条偏移轴的对应

| 偏移轴 | 公开数据支持数 | FSRA 的做法 | 验收指标 |
|---|---|---|---|
| `unseen_object_*` | 0（定义上） | 检索「同可供性」支持片段，当前帧 grounding 新物体 | 未见物品成功率、抓取位姿误差 |
| `human_*` 反向撤回 | 0 | 检测 `regressed` → 检索恢复三元组 → 条件化重做 | 撤回后步骤分恢复率、重做次数 |
| 位置/干扰物/背景 | 有少量 | 检索同任务不同布局的片段，作为几何先验 | 位置偏移下的步骤分 |

### 2.5 合规要点

- **单模型**：`θ` 是一条骨干；检索索引是数据；相关性头是同一骨干上的小头。
- **无外部模型**：不调用外部 VLM/云端 API 做检索或验证。
- **无在线学习**：不在评测期间更新权重或写共享记忆。

### 2.6 伪代码

```python
class FSRAPolicy:
    def __init__(self, backbone, memory, m=6, refresh_every=16):
        self.bb, self.mem, self.m = backbone, memory, m
        self.refresh_every, self.t = refresh_every, 0

    def reset(self, language=None):
        self.lang, self.S, self.t = language, None, 0

    def encode_query(self, obs):
        return self.bb.encode(obs, self.lang)          # 主骨干自己的编码器

    def get_action(self, obs, k):
        self.t += 1
        if self.S is None or self.t % self.refresh_every == 0:
            q = self.encode_query(obs)
            self.S = self.mem.topk(q, self.lang, self.m)   # 只读支持集
        return self.bb.decode(obs, self.lang, self.S, k)   # cross-attn over S

    def recovery(self, language, obs, subgoal):
        q = self.encode_query(obs)
        return self.mem.topk_recovery(q, language, subgoal, m=2)  # 恢复三元组
```

### 2.7 风险

检索可能把「看起来像」但「因果无关」的片段排到前面，放大公开数据的虚假相关；用相关性头、`m ≤ 8`、GSO 离线审计与「无支持集」对照实验（E204）约束。

## 3. UIP-17 · FCS（Fleet-Coordinated Serving）

### 3.1 架构

```
端口 8765..8765+N-1  →  轻量 N 端口端点（各持私有 episode 状态）
                              │  请求（obs, port_id, deadline）
                              ▼
                    截止时间感知调度器 Sched
                              │  batch（≤ max_batch，按 deadline 切）
                              ▼
                    共享推理后端（单份 θ + 检索索引 M）
                              │  每端口私有 KV/历史
                              ▼
                        返回动作块（形状/ dtype 严格按 README §3）
```

- 端口数必须与 N 完全一致；启动时自检 `8765..8765+N-1` 均可连接。
- **方案 1/2 都可**：显存够就每端口独立进程；显存紧就共享后端（UIP-17 的调度器就是方案 2 的必备件）。
- 每端口维护 `h_p = (obs 历史, KV, reset 计数, 验证器状态, 重做计数)`，**绝不跨端口**。

### 3.2 机群记忆契约（可共享 / 不可共享）

| 资源 | 共享? | 理由 |
|---|---|---|
| 模型权重 `θ` | ✅ | 同一单模型 |
| 公开/合成检索索引 `M` | ✅（只读） | 是数据，不是模型 |
| 全局归一化/校准统计 `C` | ✅ | 不含 episode 信息 |
| 每端口 KV/历史/验证器状态 | ❌ | episode 私有状态 |
| 原始观测/动作/奖励 | ❌ | 状态隔离 |
| 在线学到的样本/权重 | ❌（默认） | 破坏确定性；只允许离线合并 |

### 3.3 截止时间感知批处理

- 每个请求带 `deadline = now + B_p`；`B_p` 由阶段决定：接触密集步（插入/合盖/拉链）用小预算，远距离搬运用大预算。
- 批处理最多等 `D_flush`（如 10–20 ms），或凑满 `max_batch` 立即发；若最老请求等待超过 `fast_age`，走**单请求快路径**，不排队。
- 机群 p99 逼近预算时，UIP-13′ 把 `k` 降到 1，减少单次推理的序列长度与排队。
- 优先级：`regressed/redo` 请求 > 接触密集步 > 普通步；但**不得饿死**低优先级端口（加权公平）。

### 3.4 故障处理

- 单端口异常：重启该端口的会话，不影响其他端口；`reset()` 语义保持每 episode 一次。
- 共享后端异常：该批请求回退到上一次动作块的尾部或安全停止（零速/保持），并记录；不能拖垮全部端口。
- 端口数不匹配：启动即报错退出，避免评测端连接失败。

### 3.5 指标

`p50/p95/p99` 延迟、`Δ = max L_p − median L_p`、隔离违规数（必须 0）、吞吐、动作统计 regularity（jerk、饱和率、NaN/Inf 计数）、每端口成功率/步骤分。

```python
class FleetScheduler:
    def __init__(self, backend, N, max_batch=4, flush_ms=15, fast_age_ms=50):
        self.backend, self.N = backend, N
        self.max_batch, self.flush, self.fast_age = max_batch, flush_ms/1000, fast_age_ms/1000
        self.q, self.state = [], {p: PortState() for p in range(N)}

    def submit(self, port, obs, budget_ms):
        self.q.append(Request(port, obs, now()+budget_ms, priority=phase_priority(obs)))

    def run_once(self):
        if not self.q:
            return
        self.q.sort(key=lambda r: (r.priority, r.deadline))
        oldest = self.q[0]
        if now() - oldest.arrival > self.fast_age:
            batch = [self.q.pop(0)]                      # 快路径
        else:
            deadline = now() + self.flush
            batch = [r for r in self.q if r.arrival <= deadline][:self.max_batch]
            self.q = [r for r in self.q if r not in batch]
        outs = self.backend.batch_infer([r.obs for r in batch])  # 共享 θ
        for r, a in zip(batch, outs):
            self.state[r.port].kv = self.backend.kv_for(r.port)   # 端口私有
            send(r.port, a)
```

### 3.6 风险

批处理会抬高 p99；跨端口状态泄漏；端口数与 N 不一致；共享后端的单点故障。用「隔离审计 + 故障注入 + 延迟预算」三条护栏（E205–E207、E211）。

## 4. UIP-18 · FEX（Fleet Experiment harness）

- **用途**：用本地 N 端口复现评测端的并发形态，**离线**做 A/B 与隔离审计；绝不用于正式评测期间的自适应调参。
- **实验设计**：同一任务套件按端口分配不同配置（如 `m=2/4/8`、`k=1/4/8`、验证器阈值），分层随机化，报告均值/置信区间；尽量用相同 seed/任务配对。
- **指标**：成功率、步骤分、p99 延迟、延迟方差、隔离违规、动作 regularity、重做次数。
- **价值**：把 UIP-13′/15′/17 的参数选择从「拍脑袋」变成「有机群证据」；同时为 UIP-11 GSO 的代理分数提供真机锚点前的预筛。
- **风险**：本地 N 端口 ≠ 官方 N 台真机的网络与负载；FEX 结论只能做**相对排序**，不能当绝对成绩。

## 7. 关键推导：为什么「检索」能补偏移轴，而「再训练」不能

设测试分布 `P_test` 与公开分布 `P_pub` 的差异主要来自偏移轴 `z ∈ {unseen, human, position, distractor, background}`。公开数据对 `z` 的支持为 `s(z)`，其中 `s(unseen)=s(human)=0`。任何仅最小化 `E_{P_pub}[L]` 的模型，在 `z` 上只能靠**归纳偏置**外推；当 `z` 改变因果特征（新物体的可供性、被撤回的子目标）时，外推误差不可控。

FSRA 的做法是把 `P_test` 上的少量**无标签**观测 `o_{0:k}` 映射到支持集 `S_e`，把目标从 `π(a|o)` 变为 `π(a|o,S_e)`。只要 `S_e` 与当前 episode 共享**因果特征**（同一可供性/同一恢复模式），条件化就能把误差从「外推」降为「匹配」。这也是为什么必须先做**相关性门控**：若 `S_e` 只共享视觉表观而不共享因果特征，条件化反而放大偏差。

机群侧同理：N 端口共享 `θ` 不改变单 episode 的因果结构，但共享**调度**会改变延迟分布。延迟不是「体验问题」，而是 README §6 的可信度输入；因此 FCS 的目标不是「吞吐最大」，而是「在 `p99 ≤ B` 下吞吐最大」。

## 9. 合规、接口与风险

- **单模型合规**：所有端口共享 `θ`；检索索引是数据；不调用外部 VLM/云端模型；不做在线梯度更新。若用外部嵌入模型做检索，需改为「主骨干编码器 / 经典特征」。
- **状态隔离**：每端口 `reset`、历史、KV、验证器状态严格私有；实现后用 E207 探针审计。
- **端口数**：必须暴露恰好 N 个连续端口（8765 起）；N 未公布前做成可配置，启动自检。
- **接口红线**：动作形状/dtype/token/块长严格按 README §3；返回块长与声明不一致、NaN/Inf、动作统计异常都会伤可信度。
- **状态捷径**：训练时只喂接口可得的键（或做键丢弃增强），避免模型依赖 `torso/d435/base_command`。
- **仿真过拟合**：GSO/DRF 只做「结构/顺序/恢复」裁判；真机锚点不可省。
- **手册仍未取到**：5 轴中的「位置/干扰物/背景」细则与「评测轮次/时限/控制频率」仍待飞书手册公开后核实。

## 11. 本轮最大风险 & 押注

**一句话最大风险**：把「检索相似」误当成「任务相关」，会让 FSRA 在公开分布上越拟越像、在真正的偏移轴上仍然失效；同时机群批处理若压不住 p99，会把省下的显存换成可信度扣分。

**→ 押注：UIP-16 FSRA × UIP-01″ RHPV-D+ × UIP-17 FCS**——用检索支持集补偏移轴零样本，用滚动验证-重做兜住 `human_*` 撤回，用机群调度与隔离保证 N 端口下的可信度；三者都在选手权限内，且不引入第二个模型。
