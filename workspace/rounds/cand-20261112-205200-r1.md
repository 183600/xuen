# 第 1 轮（灵感循环 v2：「运动控制」×「技能组合」）—— 从「整体动作块重试」转向「运动契约化的技能组合」

> **本轮不推倒 v1，而是在选手权限内做一次更深的切割。** v1 的 UIP 系列把问题看成「**语义子目标是否达成 → 是否重规划**」（UIP-01 的 VLM 验证器）。但它默认了「只要语义对了，动作流就是可行的」——这正是本轮的切入点。把动作块当成不透明的向量，会漏掉长程任务里最致命的两类失败：**技能接缝处的速度/加速度跳变**，以及**抓握瞬间还在高速运动**。本轮用两个灵感词重建这一层：**运动控制**提供「可行性/平滑性」的约束语言，**技能组合**提供「长程任务 = 可复用技能的序列」的结构语言。二者交叉出的对象是——**技能边界上的运动契约（motion contract）**。

---

## 0. 事实底座（继承 v1 §0，仅保留本轮直接相关项；检索日期 2026-11-12）

- **赛制**：32 项真机桌面任务，**单模型多任务**；选手在远端把策略部署为 `observation→action` API，评测系统连接真机执行（`unibot_submission` README §1/§5）。
- **接口**：`metadata` 含 `control_space ∈ {joint, ee}`、`action_chunk_size T_a`、`obs_delta_indices`；`get_action(obs)` 返回动作块；`reset()`；观测含 4 路 480×640 图像、双臂关节/EE 位姿、夹爪、lower_body、`observation.language`。
- **排名**：**平均成功率 + 步骤分（每任务满分 100 的 Scoring Steps）**；N 端口（8765..8765+N-1）并发，逐步**响应延迟及其波动**与**动作统计规律性**计入**结果可信度**。
- **泛化轴**：位置 / 干扰物 / 背景 / 未见物品 / 人为干扰（来自用户给定，飞书正文仍未能抓取，**未复核**）。
- **尚不可核实**：「榜首成功率 <30%」与每任务具体计分点。本轮继续当作**工作假设**，不当作事实。

## 1. 直觉解释：长程失败更像「接缝问题」，而不是「语义问题」

UIP-01 的隐含假设是：模型大体知道该做什么，只是需要一个验证器告诉它「这步成了没有」。但真实桌面操作的失败常常不是「不知道抓杯子」，而是：

1. **抓握时还在动**——夹爪在速度尚未衰减时闭合，物体滑脱或弹飞；
2. **技能切换太硬**——从「伸向杯子」切到「搬到盘子」时，目标点瞬间改变，速度指令出现阶跃，真机因加速度饱和而**冲过头**；
3. **控制空间用错阶段**——自由搬运用关节空间更平滑，精细插入用 EE 空间更抗目标点漂移，但整段只用一个空间。

这三件事都属于**运动控制**层面的「接缝」，而**技能组合**恰好给了它们一个自然的表示：任务不是一整块动作，而是 `reach → grasp → lift → transport → align → place` 的技能程序；**失败集中在 `∘`（组合算子）上**。因此本轮的直觉是：**与其在推理时反复重试一个整体策略（v1 的路线），不如先把技能之间的接缝做成「物理上可行、时序上正确」的契约**——成功来自「少犯错」，而不是「多试错」。这也顺带压低动作统计异常，直接对齐可信度口径。

## 2. 严谨定义：把两个灵感词变成可计算对象

### 2.1 运动控制 = 对「发出的动作流」施加可行性约束

记 API 实际发出的动作流为 `a_{1:T} ∈ A`（`A ⊆ R^d`，joint 或 ee 增量）。底层电机/阻抗/ROS 我们**无权修改**，但我们可以决定 `a_t` 本身。定义**（软）可行性集**：

```
F = { a_{1:T} : |q_t| ≤ q_max, |q̇_t| ≤ v_max, |q̈_t| ≤ a_max,
               |a_t − a_{t−1}| ≤ J_max·Δt,  gripper 仅在允许相位切换 }
```

其中 `q_t, q̇_t` 由本体感知估计。我们真正能做的是**投影** `Π_F(a)`：对超出 `a_max/J_max` 的跳变做**限幅/限斜率**，并把抓握闭合推迟到速度低于阈值。关键可测量量是**命令跳变**

```
Δ = max_t ||a_t − a_{t−1}||
```

它既是我们能优化的物理量，也是可信度口径里「动作规律性」的代理。

**可证明的平滑长度（本轮工具性引理）**：若在 `T_b` 步内用 min-jerk 曲线 `β(τ)=10τ³−15τ⁴+6τ⁵` 把速度从 `v_i` 过渡到 `v_j`，则

```
||v̇|| ≤ 1.875·||v_j−v_i|| / T_b ,   ||v̈|| ≤ (10/√3)·||v_j−v_i|| / T_b²
```

所以要同时满足加速度 `a_max` 与加加速度 `j_max`，取

```
T_b ≥ max( T_min, 1.875·||Δv||/a_max, sqrt((10/√3)·||Δv||/j_max) )
```

这给「混合多久」一个**闭式、可标定**的答案，而不是拍脑袋的超参。

### 2.2 技能组合 = 带边界契约的程序代数

**技能**：`s = (π_s, E_s, X_s, c_s, g_s)`，其中 `π_s: O×Z → A^k` 是产生动作块的条件策略，`E_s, X_s` 是进入/退出区域（在 EE 位姿空间），`c_s ∈ {joint, ee}` 是控制空间偏好，`g_s` 是夹爪时序。**技能程序**：`π = s_1 ∘ s_2 ∘ … ∘ s_m`。**组合算子 `∘` 合法**当且仅当存在**边界契约** `C(s_i, s_{i+1}) = (T_b, ε, v_grasp)`，满足：

1. **几何可达**：`dist(X_{s_i}, E_{s_{i+1}}) ≤ ε`（否则插入一个 `reach/bridge` 技能）；
2. **速度可接**：按 2.1 的 `T_b` 公式混合，使 `||v̇|| ≤ a_max`；
3. **时序正确**：夹爪只在 `||v|| < v_grasp` 的**速度极小点**附近切换 `g_s`。

于是「技能组合」不是符号规划，而是一个**带运动学约束的程序**：`π` 的每一对相邻技能都必须通过契约检查。单模型合规性用**技能 token / 条件 LoRA** 保证：共享一个骨干，技能只是条件，不是多进程多模型。

## 3. 瓶颈假设（可证伪）

- **H1（接缝主导）**：长程失败中，由「抓握时序 + 技能切换不连续」造成的比例，高于「语义选错子目标」。→ 可用 §E 的离线回放测边界跳变与失败的相关性。
- **H2（结构省样本）**：32 任务可分解为少数共享技能（reach/grasp/transport/align/insert/pour/fold），共享技能 + 轻路由比单一整体策略更省数据，并天然抗未见物品（技能是物体无关的运动基元，目标是 VLM 落地的坐标）。
- **H3（平滑是免费排名）**：降低 `Δ` 既减少真机 overshoot，又改善可信度动作规律性，是少数「两个口径同时受益」的动作。
- **H4（组合放大小误差）**：若单个技能的终点有系统偏差，硬切换会把偏差放大成振荡；契约化的 settle + 混合能吸收它。

## 4. 候选创新点（MSP-01~08，收敛到旗舰 MSP-01）

围绕两词发散 9 个草案，合并为 8 个（产物区详述）：**MSP-01 运动契约化技能组合（旗舰）**、MSP-02 技能边界判别器、MSP-03 控制空间相位调度、MSP-04 技能条件 LoRA、MSP-05 夹爪时序契约、MSP-06 跨任务技能重组增广、MSP-07 离线运动回放 harness、MSP-08 干扰感知 settle。旗舰之所以是 MSP-01：它把「运动控制」与「技能组合」直接合成一个**可在 API 内部实现、可用离线数据验证**的机制，且不与 v1 的 UIP-01 冲突——UIP-01 的验证器正好退化成 MSP-01 里的**边界判别器**。

## 5. 本轮最大风险

**一句话**：技能分解与边界契约依赖对 32 任务逐一手工定义子目标与标定运动参数，若技能库覆盖不全或 `ε / v_grasp / T_b` 标定错误，组合层会把单个技能的小误差放大成**系统性**失败（尤其在人为干扰轴下），因此必须先用离线回放验证技能覆盖与契约有效性，再上真机。

## 1. 旗舰 MSP-01 · MCSC 的形式化

### 1.1 技能与程序

```
技能   s = (π_s, E_s, X_s, c_s, g_s)
        π_s : O × Z → A^k        （条件动作块生成器）
        E_s, X_s ⊂ SE(3)          （进入/退出区域）
        c_s ∈ {joint, ee}         （控制空间偏好）
        g_s : 时间 → {open, close}（夹爪时序）

程序   π = s_1 ∘ s_2 ∘ … ∘ s_m
契约   C(s_i, s_{i+1}) = (T_b, ε, v_grasp)
```

### 1.2 组合合法性（三条）

1. **几何**：`dist(X_{s_i}, E_{s_{i+1}}) ≤ ε`，否则插入 `bridge/reach`。
2. **速度**：按闭式 `T_b` 混合（见 §1.3），保证 `||v̇|| ≤ a_max`、`||v̈|| ≤ j_max`。
3. **时序**：`g_s` 的闭合只发生在 `||v|| < v_grasp` 且连续 `D` 步的位置（速度极小点）。

### 1.3 混合长度的闭式推导

取 min-jerk `β(τ)=10τ³−15τ⁴+6τ⁵`，`τ∈[0,1]`，`β(0)=0, β(1)=1, β'(0)=β'(1)=0`。
令 `v(t)=v_i+β(t/T_b)(v_j−v_i)`，则

```
v̇(t) = β'(τ)·(v_j−v_i)/T_b
v̈(t) = β''(τ)·(v_j−v_i)/T_b²
max_τ β'(τ) = 1.875  (τ=0.5)
max_τ |β''(τ)| = 10/√3 ≈ 5.774  (τ=(3±√3)/6)
```

故

```
T_b ≥ max( T_min, 1.875·||Δv||/a_max, sqrt((10/√3)·||Δv||/j_max) ),  Δv = v_j−v_i
```

这条式子把「混合多久」变成**由 `Δv` 与执行器限值直接决定**的量；`Δv` 越大、`T_b` 越长。真机上 `a_max, j_max` 可用一次低风险标定（小幅阶跃响应）估计，或取保守默认。

### 1.4 可行性投影 `Π_F`

对发出的每个命令做因果限斜率（slew-rate limiter）：

```
a'_t = a'_{t−1} + clip(a_t − a'_{t−1}, −J_max·Δt, +J_max·Δt)
```

再按 `v_max` 缩放、按 `q_max` 截断（由本体感知估计）。它不是严格的凸投影，而是**因果近似**：只削减高频跳变、不改变技能方向；因此**不保证绝对可行**，只降低触发执行器饱和的概率。

## 2. 运行时伪代码（MSP-01）

```python
class MCSCController:
    def __init__(self, skills, a_max=8.0, j_max=40.0, dt=0.05,
                 tol=0.03, v_grasp=0.12, dwell=3, T_min=2):
        self.skills, self.a_max, self.j_max, self.dt = skills, a_max, j_max, dt
        self.tol, self.v_grasp, self.dwell, self.T_min = tol, v_grasp, dwell, T_min

    def reset(self, program):
        self.program = program; self.i = 0
        self.v_emit = zeros(self.dim); self.buf = []
        self.settle = 0; self.blend_left = 0; self.blend_from = zeros(self.dim)

    def get_action(self, obs):
        s = self.skills[self.program[self.i]]
        if not self.buf:
            self.buf = list(s.pi(obs))          # 技能产生动作块
        if self._exit_condition(obs, s):        # 需要切换/推进
            self._advance(obs)
            s = self.skills[self.program[self.i]]
            self.buf = list(s.pi(obs))
        v_des = self.buf.pop(0)

        # (a) min-jerk 混合
        if self.blend_left > 0:
            beta = min_jerk(1 - self.blend_left / self.blend_total)
            v_des = (1 - beta) * self.blend_from + beta * v_des
            self.blend_left -= 1

        # (b) 可行性投影 Pi_F
        dv = clip_norm(v_des - self.v_emit, self.j_max * self.dt)
        a = clip_norm(self.v_emit + dv, self.v_max)

        # (c) 夹爪时序契约：仅在速度极小点闭合
        a.gripper = self._gripper_cmd(obs, s, norm(a))

        self.v_emit = a
        return a

    def _advance(self, obs):
        s_next = self.skills[self.program[self.i + 1]]
        dv = self._predicted_v(s_next, obs) - self.v_emit
        T_b = max(self.T_min,
                  1.875 * norm(dv) / self.a_max,
                  sqrt((10 / sqrt(3)) * norm(dv) / self.j_max))
        self.blend_total = self.blend_left = int(ceil(T_b / self.dt))
        self.blend_from = self.v_emit.copy()
        self.i += 1
        self.settle = 0

    def _gripper_cmd(self, obs, s, speed):
        want = s.g_s(obs.t)
        if want == "close" and speed < self.v_grasp:
            self.settle += 1
            return "close" if self.settle >= self.dwell else "open"
        self.settle = 0
        return "open"
```

单模型合规：所有 `π_s` 共享一个骨干，用 **技能 token + 条件 LoRA** 区分（MSP-04）；`program` 由 `observation.language` 经一个小语法/解析器产生，技能本身是**物体无关的运动基元**，目标点由 VLM grounding 给出——这使「未见物品」只需换 grounding，不换运动技能。

## 3. 本轮机制检验 E001/E002（合成，600 seeds/格）

脚本：`exp/msp_sim.py`；结果：`exp/msp_results.json`。任务=2D 末端按序访问 4 个 waypoint，抓握时速度越高越易滑脱；`push` 模拟人为干扰。四/五种策略做因子消融：

| push 概率 | 方法 | 成功率 | 部分完成 | 最大命令跳变均值 | 跳变 p95 |
|---|---|---|---|---|---|
| 0 | naive（到点即切/即抓） | 40.17% | 79.29% | 1.6714 | 1.7742 |
| 0 | settle（仅加时序契约） | 88.33% | 96.92% | 1.2664 | 1.2807 |
| 0 | blend（settle+混合） | 87.33% | 96.71% | **0.3617** | 0.3644 |
| 0 | **mcsc（settle+混合+限斜率）** | **88.50%** | **97.00%** | **0.3616** | **0.3646** |
| 0 | mcsc_nosettle（有平滑无时序契约） | 16.50% | 65.21% | 0.3839 | 0.4086 |
| 0.006 | naive | 35.83% | 77.83% | 1.6631 | 1.7745 |
| 0.006 | settle | **90.83%** | **97.58%** | 1.2659 | 1.2806 |
| 0.006 | blend | 90.17% | 97.33% | 0.3999 | 0.7168 |
| 0.006 | **mcsc** | 87.50% | 96.79% | **0.3661** | **0.4000** |
| 0.006 | mcsc_nosettle | 21.00% | 67.25% | 0.3858 | 0.4096 |

**读法（对本轮假设的检验）**：

1. **H1/H4 得到支持**：仅加入「速度极小点才闭合/切换」的时序契约，成功率从 40.2%→88.3%（无扰动）、35.8%→90.8%（有扰动）。接缝时序是主导项，而非语义重试。
2. **H3 得到支持**：min-jerk 混合把最大命令跳变从 1.27 降到 0.36（−71%）；再加限斜率后，**有扰动时 p95 仍被压在 0.40**（blend 无投影时 p95 反弹到 0.72）。这正是可信度「动作规律性」想要的形状。
3. **两项机制互补而非冗余**：`mcsc_nosettle`（只平滑、不 settle）在扰动下只有 21.0%，说明**没有时序契约时，平滑救不了抓握滑脱**；反过来，settle 不混合也能成功但跳变大。因此二者必须同时上。
4. **诚实的代价**：平滑 + settle 使平均步数从 32→69（更慢），且在扰动下 mcsc 的 87.5% 略低于纯 settle 的 90.8%——平滑拖慢了干扰后的再响应。这是明确的时间/平滑权衡，需用 episode 预算与步骤分共同约束。

> **边界**：这是合成机制检验，不是 UniBot 真机结果；数值只用于判断「机制方向是否成立」，不能外推为排行榜增益。

| E005 | 固定 joint/ee vs 相位调度 CPS | 各阶段成功率/抖动 | 精细插入段 ee 更优 |
| E006 | 抓握阈值 v_grasp 扫描 | 成功率 vs 平均步数 | 找时间预算下的最优阈值 |
| E007 | 端到端（MSP-01+UIP-01/02/03/08） | 榜单成功率+步骤分 | 提测后以真实榜单替换代理 |

**风险控制**：E003 必须先做，确认 32 任务的技能覆盖（若某任务如「折毛巾 / 倒药」无法分解为现有技能，则为其单独建技能，而不是硬套契约）；所有 `ε / v_grasp / T_b` 先在回放上标定，再上真机。

## 5. 与 v1 UIP 系列的关系（增量，不重复）

- **UIP-01（VLM 进度验证器）→ MSP-02（边界判别器）**：验证器从「判子目标 done/fail」升级为「判能否安全切换」；输出直接驱动 settle/blend。
- **UIP-02（步骤分安全网）→ 技能里程碑**：每个技能对应可观测里程碑，天然对齐 Scoring Steps。
- **UIP-03（LoRA 专家）→ MSP-04（技能条件 LoRA）**：专家粒度从「任务」细化到「技能」，复用性更高。
- **UIP-10（joint/ee 仲裁）→ MSP-03（相位调度）**：从任务级升级到技能相位级。
- **新增**：v1 完全没有的「动作流可行性投影 + 接缝混合 + 夹爪时序契约」，即 MSP-01/05/07。

## 6. 资源与时间线

- 第 1 周：OMR 回放 harness + 32 任务技能标注（技能集合、进入/退出区域、夹爪时序）。
- 第 2–3 周：`a_max/j_max` 标定、`T_b` 闭式实现、限斜率投影；E001/E002 已在合成上完成，迁到回放。
- 第 4–5 周：技能条件 LoRA（MSP-04）+ 边界判别器（MSP-02）；E003/E004。
- 第 6 周：相位调度 CPS（MSP-03）+ 干扰 settle（MSP-08）；E005/E006。
- 第 7 周起：预约真机提测，按 N 端口压测延迟方差，用真实榜单校准代理。

## 7. 本轮最大风险（承接想法区 §5）

**一句话**：若技能库覆盖不全或 `ε / v_grasp / T_b` 标定错误，运动契约会把单个技能的小误差系统性放大（尤其人为干扰轴），所以必须先以离线回放验证技能覆盖与契约，再上真机。
