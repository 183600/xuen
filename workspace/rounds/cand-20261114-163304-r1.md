# 第 74 轮（承接第 73 轮「MODGAUGE-RAS 计量契约代数」IP-295~302；新灵感循环第 1 轮；本轮灵感：「可靠性」×「柔顺控制」）

> R73 把证据计量做成了可组合契约：模块 = (EC, impl, cert)，组合代数 CCA（SER/PAR/VETO），反作用通道 ΣREFLEX，模块级 stub 降级，组合证书 J_MOD。它回答了「多个证据模块如何组合出一个可信的世界」。但 R73 有两处结构性盲区，恰好被本轮两个词击中：
> - **时间盲区（可靠性）**：所有契约、校准与证书都是「当前时刻」的。真实模块会老化、热漂移、卡死、给出**自信的错误值**；证书会过期；多个模块会因同一电源/温度/振动而**共因失效**。R73 的「零级联」只描述了「检测到失效的那一瞬间」的图性质，既没有回答「在 T 小时 mission 内安全论证仍然成立的概率」，也没有区分 **fail-silent（stub 能接住）** 与 **fail-active（自信地错，stub 接不住）**。可靠性不是「再加一个实验」，而是契约缺了时间维与完整性维。
> - **物理盲区（柔顺控制）**：R73 的降级链全部发生在认知域（知道得更少）。但在人机共处、接触丰富的操作中，安全还有第二种货币——**物理后果界**。柔顺（阻抗/导纳、SEA、能量罐/无源性）能在软件完全失效时仍然限制接触力，这是 stub 给不了的；反过来，柔顺会主动牺牲证据质量（软接触 → 位置/接触模式不确定、力-位对偶），是一笔**证据负债**。R73 没有「刚度」这个可调度变量，因此无法表达「当不确定度变大时，用柔顺去换后果」。
>
> 核心命题：**安全不是一维的「不确定度小」，而是二维的「证据可靠度 × 物理后果界」；柔顺是两种货币之间的兑换器，可靠性是随时间漂移的兑换率。** 把 MODGAUGE 扩展为 **RELIC-RAS**（REliability-Integrated, Impedance-Certified metrology for RAS）——可靠性与柔顺双维计量。

## 0. 直觉与动机

**灵感 1（可靠性 → 证据也有「浴盆曲线」，且失败会撒谎）**
直觉：R73 默认模块要么「活着且契约成立」，要么「坏了进 stub」。真实的证据模块有三种状态而非两种：**好**、**坏且已知（detected）**、**坏且不自知（undetected-wrong）**。第三种最致命——一个缓慢偏置的深度相机、一个卡在旧值的力传感器、一个过期的外参，会持续输出**形状正确、类型正确、预算闭合、证书齐全**的证据，让 CCA 自信地融合，而 stub 永远不会被触发。可靠性的正确抽象不是「可用率」，而是 **(可用性 A, 完整性 S)** 二维：A = P(活着)，S = P(没有在悄悄骗你)。stub 只处理 ¬A；只有内建测试（BIT）+ 跨模态审计 + **完整性预算**能处理 ¬S。可靠度还可以像不确定度一样**组合**：串联 ΠR_i（任一坏则坏），并联 1−Π(1−R_i)（冗余），但只有通过**独立性审计**才配拿到冗余 credit——否则共因（同一电源、同一温度、同一柔顺控制器）会让冗余变成自欺。**关键洞察：可靠度代数是 CCA 的序对偶**——不确定度靠 SER 相加、可靠度靠 SER 相乘；不确定度的 PAR 缩窄与可靠度的冗余 credit 都必须先过同一次一致性/独立性审计。**一次审计，服务两种货币。**

**灵感 2（柔顺控制 → 刚度是「物理否决」，也是「证据汇率」）**
直觉：柔顺控制的价值不在于「控制得更准」，而在于它提供一个**不依赖任何软件与证据的后果上界**：给定硬件刚度 K、最大穿透与速度包络，最坏接触力 F_bound(K) 有界。即使感知全瞎、估计全错、控制器发出错误指令，只要阻抗环节的物理参数与能量罐无源性成立，人受到的力就有界。这是 R73 所有 VETO 都做不到的——软件 VETO 需要「相信某个证据说情况危险」，而物理否决连「相信」都不需要。**这是安全的第二种货币。**
但柔顺不是免费的：固定界面上，从力反推位置 u_x = σ_f/K（K↓ 变差），从位置反推力 u_f = K·σ_x（K↓ 变好），两者乘积 κ = σ_xσ_f 与 K 无关——这就是**力-位对偶不确定关系**。软化把误差从力搬到位置，同时可能引入接触模式歧义（脱离/接触分不清）、滑移、力环极限环。所以刚度不是「越软越安全」，而是一条有内点的取舍曲线：**太硬 → 后果大；太软 → 证据烂且可能失稳**。

**灵感 3（两者交汇 → 可靠度-柔顺安全包络 RCSE 与物理级优雅降级）**
直觉：把两条货币放在同一张风险预算上：Risk(K, r) = Risk_phys(K)（随 K 增）+ Risk_epi(K, r)（随 K 减、随证据可靠度 r 减而增）。给定任务允许的总风险 ε_safe，**可行刚度是区间**，最优点是内点。当某模块可靠性下降（r↓），Risk_epi 整体抬升，最优刚度**向下移动**——这就是**物理级优雅降级（PGD）**：R73 的降级是「知道得更少就进入 stub」，RELIC 的降级是「知道得更少，同时推得更轻、更软」。失效不再只是损失性能，而是把安全从认知货币兑换到物理货币。这把 R73 的「零级联」补成**零认知级联 + 零后果级联**。

**灵感 4（时间 → 证书会过期，论证要积分）**
直觉：R73 的 J_MOD 是逐周期证书；真实任务要的是 **mission 级证书** J_MISSION：在 [0,T] 内，安全失效概率的积分 ≤ ε_safe·T。这需要健康状态的马尔可夫/相型（phase-type）模型、各模块风险率 λ_i(t)、证书有效期 T_i^cert、以及降级/维修动作。一旦某证书过期而任务未完，系统必须自动进入更保守的 (stub, 更软) 状态，而不是「假设它还有效」。

**灵感 5（共因与耦合 → 柔顺是跨模块共享物理变量，会毒化独立性审计）**
直觉：R73 最大的自认风险是「隐共享物理过程」。柔顺控制把这个风险从暗处拖到明处：**阻抗控制器本身就是跨模块共享变量**——同一个刚度同时决定接触模块的观测质量、执行器模块的力权限、力传感器的量程占用。因此，在柔顺介入时，PAR 的独立同分布假设必然失效。正确的做法不是假装独立，而是**以共享状态 S（阻抗、温度、振动）为条件做审计**；条件独立不成立就禁用缩窄与冗余 credit。这既是修正，也是张力：**柔顺既是安全资产，又是相关性的来源**。

**灵感 6（蒸馏 → 两条新可证伪主张）**
- **C4（可靠度感知的证据组合）**：把可靠性（可用性+完整性）作为契约的时间维并做代数组合，比 R73 的逐周期证书在同等可用率下**显著降低未被检测的错误证据率与任务级安全违例率**。
- **C5（柔顺作为安全货币）**：可靠性触发的软化调度，在模块失效/漂移下**维持安全且性能损失有界**，显著优于「硬停止」与「无柔顺」；且力-位对偶导致的证据退化可由 RCSE 预测。
这两个主张必须各有最小基准与隔离消融，否则降级为工程附件——延续 R73 的 CPB 纪律。

## 1. 形式化定义（增量：定义 383–400）

**定义 383（RELIC-RAS 总览）** RELIC-RAS = (MMS†, DPEM†, CCA†, RCA, CIC, RCSE, R²EFLEX, J_MISSION, CPB†, MODGAUGE-RAS†)。六不变式：
(i) **契约双维完整**：每个模块同时实例化 EC（认知/证据）与 ERC（时间/可靠性），缺一不入图；
(ii) **可靠度代数单调**：所有冗余/组合 credit 经 RCA 与同一次审计校验，无「凭空虚增可靠度」路径；
(iii) **物理否决独立**：CIC 的后果上界不引用任何感知/估计/证据，只引用硬件证书与阻抗状态；
(iv) **兑换单调**：软化在后果侧安全单调（K↓ ⇒ F_bound↓），且 RCSE 把可靠度状态映射为可行刚度的单调收缩；
(v) **完整性预算闭合**：Σ 未检出错误风险 ≤ ι_sys，否则不得认证（可用率不能替代完整性）；
(vi) **严格退化**：令 λ≡0、T^cert≡∞、d≡1、β≡0、K≡刚性，则 RELIC 逐指令等于 R73 MODGAUGE，再退化为 R72/R71/R68。

**定义 384（证据可靠性契约 ERC）** 模块由三元组升为五元组 (EC, impl, cert, ERC, health)：
ERC = (λ_i(t), ℱ_i, d_i, T_i^cert, ρ_health, repair_i, ι_i)，
- λ_i(t)：相型/Weibull 风险率；ℱ_i = {silent-stale, dead, biased-drift, stuck, noisy-active} 失效模式集；
- d_i: ℱ_i → [0,1] 为各模式检出覆盖（BIT + 跨模态审计 + 时序一致性）；未检出概率 1−d_i；
- T_i^cert：证书有效期（过期即视为未认证，不得被 J_MISSION 引用）；
- ρ_health：健康状态信念 b_t(h_i)，h_i ∈ {GOOD, DEGRADED, DETECTED-FAIL, UNDETECTED-WRONG}；
- repair_i：可执行的维修/重校准/降级动作集；ι_i：完整性风险预算。
**关键**：`cert` 是「出厂/校准时刻的快照」，`ERC` 是「随任务时间演化的可靠性承诺」，二者不可互相替代。

**定义 385（可靠度组合代数 RCA）** 与 CCA 对偶的三算子：
- **SER**：Λ_out = Σ_i Λ_i（令 Λ_i = −ln R_i，可靠度取乘），并加共因项：R_out = (1−β)·Π R_i + β·min_i R_i，β 为共享过程耦合因子；
- **PAR（冗余）**：仅当**独立性审计** A_ind 通过时 R_out = 1 − Π(1−R_i)；审计失败 ⇒ R_out = 1 − β(1−Π(1−R_i))，β→1 时退化为 min_i R_i（冗余无效，只能取最弱环）；
- **VETO（监视器）**：R_veto = Π_i R_monitor_i。**未被监视的否决不计 credit**——一个会静默失效的监视器比没有更危险。
语义：SER 使可靠度只降不升；PAR 只买到「经审计的」冗余；VETO 把监视器自身的可靠性变成安全论证的一部分。

**定义 386（可靠-不确定序对偶）** 令 Λ = −ln R。存在保结构对应 D：CCA 的 SER/PAR(audit)/VETO 分别映到 RCA 的 SER/PAR(audit)/VETO，且
u_out ≥ Φ(u_in) ⇔ Λ_out ≥ Φ(Λ_in)。
**推论（一次审计两用）**：conformal 跨模态一致性审计与共因独立性审计应共用同一证据流；能缩窄 u 才配拿到冗余 credit，反之亦然。**不能为一个世界做审计，却为另一个世界发证书。**

**定义 387（柔顺阻抗契约 CIC）** CIC = (Z, E_tank, 𝒫, F_bound, χ_Z, D_Z)：
- Z = (M, B, K)：笛卡尔/关节阻抗（刚度 K 为核心可调度量）；
- 𝒫：无源性/能量罐约束 E_tank(t) ≥ 0（无源性能量整形）；
- F_bound(K)：部署期由硬件证书（力矩上限、SEA 刚度、有效质量、速度/穿透包络）计算的最坏接触力量级；
- χ_Z: 𝒢 → (Θ_contact, D_Z′)：把刚度/阻尼动作显式声明为接触证据的调制通道（K↓ ⇒ 力分辨率↑、位置/接触模式不确定↑、失稳风险↑）；
- D_Z：柔顺有效域（力/位行程、能量罐下限、滑移/颤振排除区）。
CIC 是「物理模块」，与证据模块同图组合，但其否决（物理否决）不经软件证据。

**定义 388（力-位对偶不确定关系）** 固定接触界面（位移噪声 σ_x，力噪声 σ_f）：
u_x^{inf}(K) = σ_f / K，u_f^{inf}(K) = K·σ_x ⇒ u_x^{inf}·u_f^{inf} = κ ≜ σ_xσ_f（与 K 无关）。
接触证据质量不是单一标量：D_MEM 的位姿分量消耗 u_x，力/接触模式分量消耗 u_f。定义任务加权证据质量 Q_c(K) = Q_x(u_x(K)) + Q_f(u_f(K))；当任务同时需要「在哪」与「多大力」时 Q_c 对 K 有内点极大——**软化不能同时改善两者**。

**定义 389（物理否决 VETO_phys）** 对任意软件状态与任意证据，CIC 给出 |F_contact| ≤ F_bound(K) 的集合约束（在 𝒫 成立前提下）。它只能因硬件改动（换执行器/换 SEA）而失效，不能因感知/估计/证书失效而失效。定义安全侧不变量：`执行风险 ≤ F_bound(K)` 恒成立。与软件 VETO 并列：软件 VETO 管「命题真假」，物理 VETO 管「后果大小」。

**定义 390（可靠度-柔顺安全包络 RCSE）** 给定任务安全预算 ε_safe 与证据可靠度状态 r(t) = (R_i(t), b_t(h))：
Risk(K, r) = Risk_phys(K) + Risk_epi(K, r) + Risk_int(K, r)，
其中 Risk_phys 随 K 增（后果），Risk_epi 随 K 减且随 r 减而增（证据），Risk_int 为未检出错误项（由完整性预算给出，随 K 减而增，因为软接触更难区分接触模式）。
可行包络 𝒦(r) = { K ∈ D_Z : Risk(K, r) ≤ ε_safe }；调度 K*(t) = argmin_{K∈𝒦(r(t))} [Risk(K,r(t)) + λ_p·Perf⁻¹(K)]。
**弹性引理**（见引理 41）：在正则条件下 𝒦(r) 非空且为区间，r↓ ⇒ K*(t) 非增——**可靠度下降 → 刚度下降**。

**定义 391（物理级优雅降级 PGD）** R73 的降级阶梯（GOOD → stub）扩为二维阶梯：
- DETECTED-FAIL ⇒ 模块 stub（认知降级）+ RCSE 强制 K ≤ K*(r′)（物理降级）；
- DEGRADED（疑似偏差/漂移）⇒ 不 stub，但收紧 D、提高审计频率、按 b_t(h) 软化；
- UNDETECTED-WRONG 风险超 ι_i ⇒ 进入 **BLIND-SOFT**：证据降权但不假装失败，刚度锁到 K_safe0 使 F_bound < ε 与证据无关。
**失效传染路径**：该模态证据缺失（认知）+ 刚度全局下调（物理，单调安全侧）；无跨模块认知污染，无后果级联。

**定义 392（任务可靠性证书 J_MISSION）** J_MISSION = (J_MOD 的时间积分, 健康相型模型, RCSE 调度, 完整性账本)：
Valid(J_MISSION, T) ⇔ ∀t∈[0,T]：J_MOD(t) 在 b_t(h) 下有效 ∧ K(t) ∈ 𝒦(r(t)) ∧ t < min_i T_i^cert ∧ ∫_0^T P(violation; t) dt ≤ ε_safe·T。
健康状态按相型链演化，转移率由 λ_i(t)、d_i、repair_i 给出；风险在时间上按 `‑ln R` 可加性传播（RCA）。**证书过期是硬事件**：过 min T^cert 自动降级，不得沿用旧证书。

**定义 393（R²EFLEX 可靠性-柔顺反作用预算）** 在 R73 ΣREFLEX 的通道预算上增两本账：
- c_reflex：原 ψ/z/c/v 层（信息动作）；
- c_consequence = E[F_bound(K)]：物理后果成本（软化动作）；
- c_reliability = recalib + redundancy_on + perf_loss(K)：维修/冗余/软化带来的性能损失。
可行动作 = { Σc_reflex ≤ B_reflex } ∩ { Σc_consequence ≤ B_consequence } ∩ { Σc_reliability ≤ B_reliability } ∩ Ω_safe。三本账共同决定交互是否被允许；有限停止在三本账上分别成立（每本账边际成本正下界 + 总增益非增）。

**定义 394（可靠度干预价值 RVOI）** 对候选干预 a ∈ {recalibrate_i, replace_i, cross_check, soften(ΔK), redundance_on_i}：
RVOI(a) = E[Δ 任务违例风险 | a] − cost(a) − λ_b·budget_use(a)。
仅当 RVOI(a) > 0 且预算可行时执行。这是 R73 ERVOI（买信息）的**可靠性对偶**（买稳健性/买后果界）。二者共享同一预算框架，避免「为了信息而透支可靠度」或反之。

**定义 395（完整性预算与 fail-active）** 完整性风险 I_i(T) = Σ_{f∈ℱ_i} (1−d_i^f)·∫_0^T λ_i^f(t)dt；系统完整性由「未检出错误」事件的 RCA 组合（注意：未检出错误常常正相关，不能按独立算）。要求 I_sys(T) ≤ ι_sys，否则**无论可用率多高都不得认证**。区分：
- 可用性 A = P(¬dead)（stub 处理）；
- 完整性 S = P(¬undetected-wrong)（只有 BIT/跨模态/完整性预算处理）。
**这是 R73 stub 语义的正式补洞**：stub 假设 fail-silent，现实大量 fail-active。

**定义 396（共因与阻抗条件化审计）** 设共享物理状态 S = (Z, 温度, 振动, 供电, 光照)。CCA 的 PAR 缩窄与 RCA 的冗余 credit 均以 S 为条件：
A_ind(S) 通过 ⇔ 跨模态残差在给定 S 下 conformal 覆盖 ∧ 残差条件相关 |ρ_{ij|S}| < ρ_max ∧ β(S) < β_max。
柔顺使 S 中的 Z 成为**跨模块共享变量**，因此 `ρ_{ij|Z}` 可能显著非零——同一刚度既改变接触证据又改变执行器权限。审计失败即退保守（PAR: max；RCA: min），并在 ECG 上标注共享边。

**定义 397（模块运行时状态机）** 状态 ∈ {GOOD, DEGRADED, STUB, BLIND_SOFT}；转移由 b_t(h)、J_MOD 有效期、ι 账本驱动。RELIC 主闭环在 R73 三域上增两处：可靠性域（1Hz，健康更新 + RVOI + J_MISSION 推进）与柔顺调度（计量域 20–50Hz，解 RCSE 得 K*）。

**定义 398（MBench†：MB4/MB5/MB6）** MB4 可靠性（长时程故障注入、漂移/卡死/静默失效、共因场景）；MB5 柔顺（力-位对偶台架、物理否决在软件关闭下的验证、人形假体碰撞代理）；MB6 双货币（任务中注入退化 → 软化 → 安全与性能同时计量）。各 ≤3h 单卡/单台架可复现，预注册 + 密封保持集 SEAL-MB†。

**定义 399（CPB† 主张 C4/C5）**
- C4 ← (ERC, RCA, 完整性预算) ← MB4 ← AB4（可靠度代数 vs 逐周期证书 vs 仅可用率）← (未检出错误率, 任务违例率, 误报停机率)；
- C5 ← (CIC, RCSE, PGD) ← MB5/MB6 ← AB5（软化调度 vs 硬停止 vs 无柔顺）← (最坏接触力, 性能损失, 失稳/滑移率, 违例率)。
非绑定组件 = 工程附件，不入 MReg、不进正文。

**定义 400（复杂度结构上限†）** |V_M|≤24、组合深度≤4 保持；新增 |ℋ|≤4（健康态）、|𝒦| 为 RCSE 一维区间、J_MISSION 相型阶数 ≤ min(8, |V_M|)。运行时可靠性更新 O(|V_M|·|ℋ|)，mission 离线 rollout O(|V_M|·H)，RCSE 求解 O(1)（一维单峰搜索）。

```python
# IP-303 ERC/RCA：可靠性契约与可靠度组合
@dataclass(frozen=True)
class ReliabilityContract:
    hazard: Callable[[float], float]        # λ_i(t) 相型/Weibull
    failure_modes: FrozenSet[str]           # silent/dead/biased/stuck/noisy
    detect_cov: Dict[str, float]            # d_i^f (BIT + 跨模态)
    cert_horizon_s: float                   # T_i^cert
    integrity_budget: float                 # ι_i
    repair_actions: FrozenSet[str]

def rca_compose(a, b, op, S, beta_S):
    if op == 'SER':
        R = (1-beta_S)*a.R*b.R + beta_S*min(a.R, b.R)      # 共因项
        return R, a.Lambda + b.Lambda
    if op == 'PAR':
        if not audit_independence(a, b, S):                # 条件独立审计失败
            return min(a.R, b.R), None                     # 冗余 credit 归零
        R = 1 - (1-a.R)*(1-b.R)
        return R, -math.log(R)
    if op == 'VETO':                                       # 监视器必须自身可靠
        return a.R*b.R, None

def integrity_risk(rc, T):                                 # 定义 395
    return sum((1-rc.detect_cov[f]) * rc.hazard_int(f, T)
               for f in rc.failure_modes)

# IP-304 CIC：柔顺阻抗契约与力-位对偶
class CompliantImpedanceContract:
    def force_bound(self, K):                              # 物理否决：不引用感知
        return self.hw.certified_force_bound(K, self.v_max, self.m_eff)
    def evidence_quality(self, K, task_w):
        ux = self.sigma_f / K                              # 位置反推
        uf = K * self.sigma_x                              # 力反推
        return task_w.x/q(ux) + task_w.f/q(uf), (ux, uf)    # 内点最优
    def admissible(self, K):
        return self.energy_tank_ok(K) and self.domain.contains(K)

# IP-305 RCSE + PGD：可靠度-柔顺安全包络与物理级优雅降级
def rcse_schedule(belief, modules, task, budget):
    def risk(K):
        return (risk_phys(K) + risk_epi(K, belief) + risk_integrity(K, belief))
    grid = np.linspace(task.K_min, task.K_max, 33)
    feas = [K for K in grid if risk(K) <= budget.eps_safe and cic.admissible(K)]
    if not feas: return None                               # 无可行刚度 → 拒绝任务
    K_star = min(feas, key=lambda K: risk(K) + task.lam_p/perf(K))
    return K_star, feas                                    # 区间（弹性引理 41）

def pgrede_step(mod, health, K_cmd):
    if health == 'DETECTED-FAIL': return stub(mod), min(K_cmd, rcse.Kstar_degraded)
    if health == 'DEGRADED':      return tighten(mod.domain), min(K_cmd, rcse.Kstar_deg)
    if health == 'UNDETECTED-WRONG_RISK': return blind_soft(mod), rcse.K_safe0
    return mod, K_cmd

# IP-306 J_MISSION：任务级可靠性证书
def j_mission_step(state, dt):
    state.belief = health_markov_step(state.belief, dt)    # 相型链
    state.integral += violation_prob(state.belief, state.K, dt) * dt
    state.valid = (state.integral <= state.eps_safe*state.t) \
                  and all(state.t < m.cert_horizon_s for m in state.modules) \
                  and state.K in rcse.feasible(state.belief)
    return state

# IP-307 RVOI / R2EFLEX：可靠性干预价值与三本账
def rvoi(candidates, belief, budget):
    scored = [(a, expected_risk_reduction(a, belief) - cost(a) - lam_b*budget_use(a))
              for a in candidates]
    return max((s for s in scored if s[1] > 0), key=lambda s: s[1], default=None)

def r2eflex_step(modules, g, K, state, budgets):
    for m in modules:
        c_ref = m.reflex_cost(state[m], m.ec.chi_R(g))
        c_con = expected_force(K)
        c_rel = m.reliability_cost(state[m]) + perf_loss(K)
        if not budgets.admit(c_ref, c_con, c_rel): return None
    return budgets.commit(c_ref, c_con, c_rel)

# IP-309 RELIC 主闭环（在 MODGAUGE 三域上增可靠性域与柔顺调度）
def RELIC_round(M, obs, audio, tac_frame, depth_img):
    # 感知域 100Hz
    d_ev = M.dpe.update(...);  t_ev = M.dmem.update(...)
    # 计量域 50Hz
    if M.clock.due_metric():
        b_t = M.bse.step_full(..., d_ev=d_ev, t_ev=t_ev)
        z_dist, *_ = M.irl.update(...)
        K_star, feas = rcse_schedule(M.belief, M.mods, M.task, M.budget)
        if K_star is None: return reject_task()            # 无安全刚度
        g = M.ervoi.choose(...); a = rvoi(M.repair_actions, M.belief, M.budget)
        M.mreg.audit(S=M.shared_state)                     # 阻抗条件化审计
        M.snapshot.write(b_t, z_dist, d_ev, t_ev, K_star, M.belief)
    # 可靠性域 1Hz
    if M.clock.due_reliability():
        M.belief = health_update(M.belief, M.bit, M.cross_modal)
        M.jmis = j_mission_step(M.jmis, M.dt)
        if not M.jmis.valid: M.enter_blind_soft()          # 证书失效 → 物理降级
    # 控制域 1kHz：K_star 经阻抗环执行；物理否决独立于本循环
    snap = M.snapshot.read_latest()
    k = M.ach.certified_prefix(..., K=snap.K_star)
    M.impedance.command(snap.K_star)                       # 物理层
    return k, snap.K_star, M.jmis
```

## 3. 推导

**引理 38（可靠-不确定序对偶）** 令 Λ_i = −ln R_i。SER 下 u 满足 u_out ≥ u_A + L_B u_A（CCA），而 Λ_out = Λ_A + Λ_B（RCA），二者同为「不可逆相加」；PAR 下 u 的缩窄与冗余 credit 都由同一 A_ind(S) 门控；VETO 二者都是合取。故 D 保序。系：**审计结构应统一——同一次条件独立性/一致性审计同时决定「能否缩窄不确定度」与「能否计入冗余可靠度」**，否则会出现「不确定度按独立算、可靠度按独立 credit、但物理上正相关」的双重高估。

**引理 39（力-位对偶）** 固定界面下 u_x^{inf}=σ_f/K、u_f^{inf}=Kσ_x，乘积 κ=σ_xσ_f 恒定。故任何 K 都不能同时最小化位置与力不确定度；任务同时需要两者时 Q_c(K) 存在内点最优。系：**柔顺不是免费的传感器升级，而是把误差在力/位两轴间重新分配**；KL/接触模式项必须在 u_f 轴上记账。

**引理 40（软化的后果单调性与风险单峰）** 在固定速度/穿透包络与无源性下 F_bound(K) 对 K 非减（准静态 F=Kδ，穿透 δ 有界；峰值项随 K 增），故 K↓ ⇒ Risk_phys↓；同时 u_x=σ_f/K 随 K↓ 增 ⇒ Risk_epi↑、接触模式歧义 ↑ ⇒ Risk_int↑。若 Risk_phys 在 K→K_max 时超界、Risk_epi+Risk_int 在 K→0 时超界，则 Risk(K) 单峰，可行集为区间。系：**「越软越安全」是错的；安全的是「在包络内的软」**。

**引理 41（RCSE 弹性：可靠度下降 ⇒ 刚度下降）** 在 Risk_epi 对 r 单调（r↓ 使风险曲线上移）且满足单交叉（single-crossing）条件下，argmin 随 r↓ 非增（单调比较静态）。证明用 Topkis/单交叉：风险函数族在 K 上满足递增差。系：**物理级优雅降级有解析方向，不需要在线搜索整张表**；r 的下降直接映射为 K* 的下调量。

**引理 42（完整性下界与监视器自指）** I_i(T) = Σ(1−d_f)∫λ_f 是未检出错误风险的保守下界（假设失效模式可枚举、BIT 覆盖可测）；若 VETO 监视器自身以概率 (1−d_mon) 静默失效，则有效完整性必须再乘/加监视器失效项，且该项**不能**由被监视模块的证据补偿。系：**「安全的否决」必须先被独立地证明其自身可靠**，否则 VETO 是装饰。

**定理 30（RELIC 严格包含 MODGAUGE）** 令 λ≡0、T^cert≡∞、d≡1、β≡0、K≡K_rigid（F_bound 视为无穷大/不启用），则 ERC 退化为无信息、RCA 退化为平凡真、CIC 退化为刚性执行器、RCSE 退化为全空间、J_MISSION 退化为逐周期 J_MOD。由定义 383(vi) 与 R73 引理 35，RELIC 逐指令等于 MODGAUGE，再退化等于 R72/R71/R68。**安全侧只增不减。**

**定理 31（双货币安全定理）** 若 Valid(J_MISSION,T)，则任务违例概率
P(violation over [0,T]) ≤ ε_epi(r) + ε_phys(K) + ε_int(r)
且 **ε_phys 项在全部证据/估计/控制软件失效时仍成立**（仅依赖 CIC 硬件证书与无源性 𝒫）。ε_epi 由 R73 审计给出，ε_int 由完整性预算给出。取三者之和 ≤ ε_safe。**证明的关键不是概率论，而是「物理项与软件项的可分离性」——这也是本方案最强的地方。** 其成立条件：CIC 的硬件模型（饱和/摩擦/能量罐）在分布内、且人/环境的力学未超出 F_bound 假设。

**定理 32（零后果级联）** 任一模块进入 DETECTED-FAIL/DEGRADED/UNDETECTED-WRONG 时，PGD 保证：(a) 认知侧按 R73 定理 29 零级联（stub 不污染 PAR）；(b) 物理侧刚度只向安全方向单调下调（引理 40/41），后果上界与证据状态解耦。故不存在「一个模块坏了 → 其他模块被污染 → 后果无界」的路径。系：**R73 的零级联补上了「后果」这一半。**

**定理 33（共因修正的保守性）** 若真实条件相关为 ρ_{ij|S} ≥ 0 而系统按独立计算 PAR 缩窄与冗余 credit，则可靠度被高估、不确定度被低估，误差上界由 β(S) 与 |ρ_{ij|S}| 控制；采用定义 396 的条件审计后，组合结果是真实值的保守上界（可靠度下界/不确定度上界）。系：**把 R73 的头号风险变成一个可度量的 β 参数，而不是拒答。**

## 6. 本轮最大风险

**一句话**：RELIC 把「最后一道防线」押在柔顺的**物理后果界**上，而这个界本身是一个未经计量审计的硬件模型假设——一旦执行器饱和、SEA 摩擦/滞回、能量罐耗尽、接触动力学或人体力学超出 F_bound 的建模范围，物理否决就什么也否决不了；此时系统反而会因为它「相信自己有一层不依赖软件的保证」而比 R73 更敢行动，把信任从可审计的证据悄悄转移到了不可审计的硬件上。

次级风险与缓解：
1. **软接触引入新失效模式（颤振/滑移/力环极限环）** → D_Z 显式排除失稳区 + E399/E411 前沿验证 + 能量罐监测作为独立否决。
2. **可靠性模型（λ/β/d）本身过拟合或错误** → 相型模型带保守上界 + SEAL-Reliability 保持集 + 部署后在线校准；只允许用实测更新、不允许用假设放宽。
3. **完整性预算漏掉未知失效模式（unknown unknown）** → 跨模态审计 + 异常检测作为「未知模式」的通用兜底；ι_sys 预留 unknown 份额。
4. **软化与任务需求冲突（必须精确/必须用力）** → RCSE 无可行解时显式拒绝任务，而不是偷偷降级；RVOI 优先买可靠性而非买性能。
5. **J_MISSION 积分误差/相型截断** → 相型阶数上限 + 数值误差预算进证书；预测-实测覆盖率作为验收（E403）。
6. **共因 β 估计不可辨识** → 环境级独立传感 + 怀疑相关即禁用 credit（保守退化为 min）而非估计。
7. **物理否决与软件否决冲突** → 取二者更保守者；物理层永远不可被软件「覆盖」，只能被硬件改动撤销。
8. **CPB 蒸馏失真（C4/C5 掩盖系统性贡献）** → 保留 R73 的 C1–C3，新增主张只做增量归因，不重写旧结论。

**本轮最大风险（一句话）**：当柔顺的物理后果界只是「建模的保证」而非「被审计的保证」时，RELIC 会把安全信心从诚实的证据不确定度，转移到一层未经证伪的硬件乐观假设上——越柔顺，越像是安全，越可能只是把风险藏进了模型误差里。

> 承接第 73 轮 IP-295~302（MODGAUGE-RAS：MMS/DPEM/CCA/ΣREFLEX/CPB/ECG/MIC）。R73 把证据计量做成可组合契约，但契约只有「当前时刻」与「认知维度」：没有时间/失效维度，也没有物理后果维度。本轮以「可靠性 × 柔顺控制」补齐这两个维度：
> - **ERC**：证据可靠性契约——模块五元组 (EC, impl, cert, ERC, health)；失效模式、检出覆盖、证书有效期、完整性预算；

> - **RCSE**：可靠度-柔顺安全包络——r↓ ⇒ K*↓，物理级优雅降级；
> - **R²EFLEX**：三本账反作用预算（信息/后果/可靠性）+ RVOI；
> - **J_MISSION**：任务级可靠性证书（时间积分 + 证书过期 + 完整性账本）；
> - **CPB†**：新增可证伪主张 C4（可靠度感知证据组合）与 C5（柔顺作为安全货币），延续蒸馏纪律。
>
> 核心命题：**安全 = 证据可靠度 × 物理后果界；柔顺是两种货币的兑换器，可靠性是随时间漂移的兑换率。**

## 2. 形式化定义（要点版）

**定义 383（总览与六不变式）** 契约双维完整 / 可靠度代数单调 / 物理否决独立 / 兑换单调 / 完整性预算闭合 / 严格退化（λ=0、T^cert=∞、d=1、β=0、K=刚性 ⇒ 等于 R73）。

**定义 384（ERC）** 模块五元组；失效模式 ℱ={silent-stale, dead, biased-drift, stuck, noisy-active}；`cert` 是校准快照，`ERC` 是随任务演化的可靠性承诺，不可互替。

**定义 385（RCA）** SER：Λ_out=ΣΛ_i，共因 R_out=(1−β)ΠR_i+β·min R_i；PAR：仅 A_ind(S) 通过时 R_out=1−Π(1−R_i)，否则退化 min；VETO：R=ΠR_monitor，未监视的否决不计 credit。

**定义 386（可靠-不确定对偶）** D: CCA→RCA 保序；**一次审计两用**——能缩窄 u 才配拿冗余 credit，反之亦然。

**定义 387（CIC）** 阻抗契约 + 能量罐 + 无源性；F_bound(K) 仅由硬件证书给出；χ_Z 声明 K 如何调制接触证据。

**定义 388（力-位对偶）** u_x^{inf}=σ_f/K、u_f^{inf}=Kσ_x、乘积 κ 恒定；Q_c(K) 内点最优。

**定义 389（物理否决）** |F_contact|≤F_bound(K) 不依赖软件；只能被硬件改动撤销。

**定义 390（RCSE）** 风险三项分解；𝒦(r) 可行区间；K*=argmin[Risk+λ_p·Perf⁻¹]；r↓⇒K*↓（引理 41）。

**定义 391（PGD）** DETECTED-FAIL⇒stub+软化；DEGRADED⇒收紧域+软化；UNDETECTED-WRONG 风险超限⇒BLIND_SOFT（K_safe0 使后果与证据解耦）。

**定义 392（J_MISSION）** Valid ⇔ ∀t: J_MOD 有效 ∧ K(t)∈𝒦(r(t)) ∧ t<min T^cert ∧ ∫P(violation)≤ε_safe·T。

**定义 393（R²EFLEX）** 三本账：Σc_reflex≤B_reflex，Σc_consequence≤B_consequence，Σc_reliability≤B_reliability，交 Ω_safe；三账分别有限停止。

**定义 394（RVOI）** RVOI(a)=E[Δ风险]−cost−λ_b·budget；仅正且可行时执行；与 ERVOI 共享预算。

**定义 395（完整性预算）** I_i=Σ_f(1−d_f)∫λ_f；I_sys≤ι_sys 否则不认证；A=P(¬dead)（stub 管），S=P(¬undetected-wrong)（BIT/跨模态管）。

**定义 396（共因与阻抗条件化审计）** A_ind(S)：给定 S=(Z,温度,振动,供电,光照) 的 conformal 覆盖 ∧ |ρ_{ij|S}|<ρ_max ∧ β(S)<β_max；柔顺使 Z 成为跨模块共享变量，审计失败即退保守。

**定义 397（运行时状态机）** {GOOD, DEGRADED, STUB, BLIND_SOFT}；RELIC 增可靠性域 1Hz 与柔顺调度 20–50Hz。

**定义 398（MBench†）** MB4 可靠性（长时程/漂移/静默失效/共因）；MB5 柔顺（力-位台架/软件关闭下的物理否决/人体代理）；MB6 双货币（退化→软化→安全+性能）；各 ≤3h 可复现 + SEAL-MB†。

**定义 399（CPB†）** C4←(ERC,RCA,IB)←MB4←AB4←(未检出错误率,任务违例率,误报停机率)；C5←(CIC,RCSE,PGD)←MB5/MB6←AB5←(最坏接触力,性能损失,失稳/滑移率,违例率)。非绑定=工程附件。

**定义 400（复杂度上限†）** |V_M|≤24、深度≤4、|ℋ|≤4；运行时 O(|V_M|·|ℋ|)；J_MISSION 相型阶数≤min(8,|V_M|)；RCSE 一维单峰 O(1)。

## 3. 关键算法伪代码

```python
# IP-303 ERC/RCA：可靠性契约与可靠度组合
@dataclass(frozen=True)
class ReliabilityContract:
    hazard: Callable[[float], float]        # λ_i(t) 相型/Weibull
    failure_modes: FrozenSet[str]           # silent/dead/biased/stuck/noisy
    detect_cov: Dict[str, float]            # d_i^f (BIT + 跨模态)
    cert_horizon_s: float                   # T_i^cert
    integrity_budget: float                 # ι_i
    repair_actions: FrozenSet[str]

def rca_compose(a, b, op, S, beta_S):
    if op == 'SER':
        R = (1-beta_S)*a.R*b.R + beta_S*min(a.R, b.R)      # 共因项
        return R, a.Lambda + b.Lambda
    if op == 'PAR':
        if not audit_independence(a, b, S):                # 条件独立审计失败
            return min(a.R, b.R), None                     # 冗余 credit 归零
        R = 1 - (1-a.R)*(1-b.R)
        return R, -math.log(R)
    if op == 'VETO':                                       # 监视器自身必须可靠
        return a.R*b.R, None

def integrity_risk(rc, T):                                 # 定义 395
    return sum((1-rc.detect_cov[f]) * rc.hazard_int(f, T)
               for f in rc.failure_modes)

# IP-304 CIC：柔顺阻抗契约与力-位对偶
class CompliantImpedanceContract:
    def force_bound(self, K):                              # 物理否决：不引用感知
        return self.hw.certified_force_bound(K, self.v_max, self.m_eff)
    def evidence_quality(self, K, task_w):
        ux = self.sigma_f / K                              # 位置反推
        uf = K * self.sigma_x                              # 力反推
        return task_w.x/q(ux) + task_w.f/q(uf), (ux, uf)    # 内点最优
    def admissible(self, K):
        return self.energy_tank_ok(K) and self.domain.contains(K)

# IP-305 RCSE + PGD：可靠度-柔顺安全包络与物理级优雅降级
def rcse_schedule(belief, modules, task, budget):
    def risk(K):
        return risk_phys(K) + risk_epi(K, belief) + risk_integrity(K, belief)
    grid = np.linspace(task.K_min, task.K_max, 33)
    feas = [K for K in grid if risk(K) <= budget.eps_safe and cic.admissible(K)]
    if not feas: return None                               # 无可行刚度 → 拒绝任务
    K_star = min(feas, key=lambda K: risk(K) + task.lam_p/perf(K))
    return K_star, feas                                    # 区间（引理 41）

def pgrede_step(mod, health, K_cmd):
    if health == 'DETECTED-FAIL': return stub(mod), min(K_cmd, rcse.Kstar_degraded)
    if health == 'DEGRADED':      return tighten(mod.domain), min(K_cmd, rcse.Kstar_deg)
    if health == 'UNDETECTED-WRONG_RISK': return blind_soft(mod), rcse.K_safe0
    return mod, K_cmd

# IP-306 J_MISSION：任务级可靠性证书
def j_mission_step(state, dt):
    state.belief = health_markov_step(state.belief, dt)    # 相型链
    state.integral += violation_prob(state.belief, state.K, dt) * dt
    state.valid = (state.integral <= state.eps_safe*state.t) \
                  and all(state.t < m.cert_horizon_s for m in state.modules) \
                  and state.K in rcse.feasible(state.belief)
    return state

# IP-307 RVOI / R2EFLEX：可靠性干预价值与三本账
def rvoi(candidates, belief, budget):
    scored = [(a, expected_risk_reduction(a, belief) - cost(a) - lam_b*budget_use(a))
              for a in candidates]
    return max((s for s in scored if s[1] > 0), key=lambda s: s[1], default=None)

def r2eflex_step(modules, g, K, state, budgets):
    for m in modules:
        c_ref = m.reflex_cost(state[m], m.ec.chi_R(g))
        c_con = expected_force(K)
        c_rel = m.reliability_cost(state[m]) + perf_loss(K)
        if not budgets.admit(c_ref, c_con, c_rel): return None
    return budgets.commit(c_ref, c_con, c_rel)

# IP-309 RELIC 主闭环（在 MODGAUGE 三域上增可靠性域与柔顺调度）
def RELIC_round(M, obs, audio, tac_frame, depth_img):
    # 感知域 100Hz
    d_ev = M.dpe.update(...);  t_ev = M.dmem.update(...)
    # 计量域 50Hz
    if M.clock.due_metric():
        b_t = M.bse.step_full(..., d_ev=d_ev, t_ev=t_ev)
        z_dist, *_ = M.irl.update(...)
        K_star, feas = rcse_schedule(M.belief, M.mods, M.task, M.budget)
        if K_star is None: return reject_task()            # 无安全刚度
        g = M.ervoi.choose(...); a = rvoi(M.repair_actions, M.belief, M.budget)
        M.mreg.audit(S=M.shared_state)                     # 阻抗条件化审计
        M.snapshot.write(b_t, z_dist, d_ev, t_ev, K_star, M.belief)
    # 可靠性域 1Hz
    if M.clock.due_reliability():
        M.belief = health_update(M.belief, M.bit, M.cross_modal)
        M.jmis = j_mission_step(M.jmis, M.dt)
        if not M.jmis.valid: M.enter_blind_soft()          # 证书失效 → 物理降级
    # 控制域 1kHz：K_star 经阻抗环执行；物理否决独立于本循环
    snap = M.snapshot.read_latest()
    k = M.ach.certified_prefix(..., K=snap.K_star)
    M.impedance.command(snap.K_star)                       # 物理层
    return k, snap.K_star, M.jmis
```

## 4. 推导

**引理 38（可靠-不确定序对偶）** 令 Λ_i=−ln R_i。SER 下 CCA 的 u 相加与 RCA 的 Λ 相加同构；PAR 的缩窄与冗余 credit 同由 A_ind(S) 门控；VETO 二者皆合取。故 D 保序。系：**同一次审计同时决定「能否缩窄不确定度」与「能否计冗余可靠度」**，否则出现双重高估。

**引理 39（力-位对偶）** u_x^{inf}=σ_f/K、u_f^{inf}=Kσ_x，乘积 κ=σ_xσ_f 恒定；任务同时需要位置与力时 Q_c(K) 内点最优。系：**柔顺是在力/位两轴间重新分配误差**，接触模式项必须在 u_f 轴记账。

**引理 40（软化后果单调、风险单峰）** F_bound(K) 对 K 非减 ⇒ K↓⇒Risk_phys↓；但 u_x=σ_f/K 随 K↓ 增 ⇒ Risk_epi/Risk_int↑。两端超界时 Risk(K) 单峰、可行集为区间。系：**安全的不是「越软」，而是「包络内的软」**。

**引理 41（RCSE 弹性）** Risk_epi 对 r 单调且风险族对 (K,r) 满足单交叉 ⇒ argmin 随 r↓ 非增（Topkis/单调比较静态）。系：**物理级优雅降级有解析方向**，无需在线全表搜索。

**引理 42（完整性下界与监视器自指）** I_i=Σ(1−d_f)∫λ_f 为未检出错误的保守下界；监视器以 (1−d_mon) 静默失效时，有效完整性须再加监视器项且**不可由被监视模块证据补偿**。系：**否决必须先被证明自身可靠**。

**定理 30（RELIC 严格包含 MODGAUGE）** λ=0、T^cert=∞、d=1、β=0、K=刚性 ⇒ ERC/RCA/CIC/RCSE/J_MISSION 全部退化；由 R73 引理 35 与定义 383(vi)，RELIC 逐指令等于 R73，再退化等于 R72/R71/R68。**安全侧只增不减。**

**定理 31（双货币安全定理）** Valid(J_MISSION,T) ⇒ P(violation)≤ε_epi(r)+ε_phys(K)+ε_int(r)，且 **ε_phys 在全部软件失效时仍成立**（仅依赖 CIC 硬件证书与无源性）。成立条件：CIC 硬件模型在分布内、人体/环境力学不超 F_bound 假设。

**定理 32（零后果级联）** DETECTED-FAIL/DEGRADED/UNDETECTED-WRONG 下，认知侧按 R73 定理 29 零级联；物理侧刚度只向安全方向单调下调（引理 40/41），后果上界与证据解耦。系：**R73 的零级联补上「后果」这一半。**

**定理 33（共因修正的保守性）** 真实 ρ_{ij|S}≥0 而按独立计算时，可靠度被高估、不确定度被低估，误差由 β(S)、|ρ_{ij|S}| 控制；采用定义 396 的条件审计后，结果为真实值的保守上界。系：**把 R73 头号风险变成可度量 β 参数，而非拒答。**

## 8. 本轮最大风险

**一句话**：RELIC 把最后一道防线押在柔顺的**物理后果界**上，而这个界本身是未经计量审计的硬件模型假设——执行器饱和、SEA 摩擦/滞回、能量罐耗尽、接触/人体动力学超出 F_bound 建模范围时，物理否决什么也否决不了；系统反而会因为「相信自己有一层不依赖软件的保证」而比 R73 更敢行动，把信任从可审计的证据悄悄转移到不可审计的硬件乐观假设里。

次级风险与缓解：
1. **软接触新失效（颤振/滑移/极限环）** → D_Z 排除失稳区 + 能量罐独立否决 + E399/E411。
2. **λ/β/d 模型错误** → 相型保守上界 + SEAL-Reliability 保持集 + 只允许实测收紧、不许假设放宽。
3. **未知失效模式** → 跨模态异常检测兜底 + ι_sys 预留 unknown 份额。
4. **软化与精度需求冲突** → 无可行 K 时显式拒任务；RVOI 优先买可靠性。
5. **J_MISSION 数值误差** → 相型阶数上限 + 误差预算入证书 + E403 覆盖率验收。
6. **β 不可辨识** → 环境级独立传感 + 怀疑相关即退 min（保守）。
7. **物理/软件否决冲突** → 取更保守者；物理层不可被软件覆盖。
8. **CPB 蒸馏失真** → C1–C3 保留，C4/C5 只做增量归因。

**最大风险（一句话）**：当柔顺的物理后果界只是「建模的保证」而非「被审计的保证」时，RELIC 会把安全信心从诚实的证据不确定度，转移到一层未经证伪的硬件乐观假设上——越柔顺，越像是安全，越可能只是把风险藏进了模型误差里。
