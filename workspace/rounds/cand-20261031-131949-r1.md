# 第 13 轮 · H-GRASP：官方 94 个评分步骤就是任务图，33k 成功演示就是抓取先验，安全-恢复层守住长程进度

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新一轮灵感循环第 1 轮（总第 13 轮），三个词是「分层规划」「抓取位姿估计」「安全性」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是补上它们缺的两端：**入口的抓取**和**出口的恢复**，并把官方公开的 94 个评分步骤直接当作高层任务图。

## 0. 先给结论：榜单撤下之后，真正的信号是 94 个官方评分步骤

先纠正一个本轮必须纠正的前提。你给的「榜首成功率也不到 30%」在 **2026-10-28 的预览 JSON** 里成立，但截至 **2026-10-31**：

1. 官网首页、`leaderboard.html`、`runs.html` 三处都已显示「即将发布 Coming Soon」，实时榜单已被撤下；
2. `leaderboard_data.json` 仍可访问，内容与 10-28 相同（MolmoAct2 29.7% 仍排第一），但它的 `generated_from` 是 `gen_leaderboard.py`，任务名还是旧版（如 JSON 里的 `Arrange Test Tubes` 对应官方 `organize_test_cube`，`Store Racket` 对应 `store_racket`）；
3. 第 12 轮在这个 JSON 上复算过：8 个模型 ×32 任务的 `step ~ success` 回归 **R² > 0.999999、最大残差 <0.006**，成功率不是 10% 的整数倍，跨模型任务相关平均只有 **0.098**。这不是实测榜单，是脚本生成的预览。

所以本轮**不把 29.7% 当 SOTA，也不把榜单任务排名当难度表**。真正的、可验证的信号是官网任务页背后的 `tasks_v2/<slug>/info.json`：**32 个任务、94 个评分步骤、四种固定分值模板、30 个任务带 human_1/human_4 扰动备注、23 个任务带未见物品备注**。这是我们第一次拿到官方的、带分值的任务图，而不是从任务名猜步骤。

我的判断是：榜首都不到 30%（如果这个预览有参考价值）不是「模型不够大」，而是 **一次运行有三道门，之前的方案只修了中间一道**：

1. **入口门：抓错**。抓杯身而不是杯把、抓网线而不是插头、抓盒盖而不是盒身、抓拉链布而不是拉链头。抓错之后，后面的伺服再准也没用；而且夹爪已经占住，VLA 很难在同一个 chunk 里改抓。
2. **中间门：最后 3 厘米**。第 12 轮 CHUNK-SERVO 已经给了答案：30 步规划 + 5 步视觉伺服 + 演示检索相对目标。
3. **出口门：做完不验证、被人改动不恢复**。官方 20% 的 trials 是人为干扰；human_1 多在抓取前移动物体，human_4 多在抓取后移动物体/受器，甚至把状态逆转（拉开的拉链再拉上、叠好的毛巾翻开、合上的笔盒打开、拧开的瓶盖拧回、叠好的第二个碗拿走）。只做「急停」不够，要做「检测 → 回滚 → 重做」。

因此本轮的押注是 **H-GRASP**：

> **用官方 94 个评分步骤做任务图（不训第二个高层 planner），用 33k 条成功演示挖「任务导向抓取相对位姿」先验（不做通用 6D 物体位姿网络），用 QP/CBF + 任务状态后验 + 不可逆动作门控做安全-恢复层（不只做急停）；VLA 仍然是唯一学习模型，抓取/安全/恢复都是确定性控制器或同一 checkpoint 的辅助头。**

一句话：**把「预测整段动作」改成「按官方步骤图执行：先抓对，再伺服最后 3 厘米，最后验证并回滚」。**

三个可验证创新点：

1. **官方步骤图（Official Step Graph）**：把 94 个评分步骤解析成带前置/后置条件、分值、抓取目标、放置目标、不可逆标记的任务图；VLA 用步骤描述做条件，监控器用后置条件推进/回滚。验证：步骤条件化是否优于整任务条件化；步骤级得分是否可预测。
2. **任务导向抓取先验（Task-Oriented Grasp Prior）**：从成功演示的夹爪闭合时刻挖 `T_obj_ee*`，按任务/步骤/物体聚类；在线用检索 + 几何评分 + 任务兼容性选抓取；可选在同一 WLA checkpoint 上加抓取头（C3）。验证：首次抓取成功率、抓取位姿误差、长程任务复合成功率。
3. **安全-恢复包络（Safety-Recovery Envelope）**：QP/CBF 管物理安全，任务状态后验管「有没有白做」，不可逆动作门控管「倒水/上锁/拉拉链/合盖」；human_1/human_4 备注直接当扰动测试集。验证：扰动检测延迟、回滚恢复率、安全违规率、以及「不过度急停」的成功率。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **分层规划** | 官方 94 步任务图 + 步骤条件化 VLA + 确定性进度监控/回滚；L3 任务层（1–5Hz）/ L2 抓取层（5–10Hz）/ L1 伺服层（30Hz，5 步 chunk）/ L0 安全层（每 chunk） | 不训第二个 VLM/LLM planner；不做 32 个任务各一个策略；不把「规划」当成从零学 94 步 |
| **抓取位姿估计** | 33k 成功演示的抓取相对位姿先验 + 反平行几何候选 + 任务兼容/稳定/可达/碰撞/可见/人距评分；可选同 checkpoint 抓取头 | 不做通用 6D 物体位姿网络；不假设 API 有深度；不把「抓起来」当终点，抓取后还要验证 |
| **安全性** | QP/CBF 物理约束 + 任务状态后验 + 不可逆动作门控 + 扰动回滚；风险感知的安全裕度 | 不只做急停；不做第二个安全学习模型；不用「人检测器」硬识别人类 |

### 1.2 官方任务 JSON：32 任务、94 步骤、四种固定分值模板

官网任务页由 `tasks_v2/<slug>/info.json?v=2026-07` 驱动。每个 JSON 含：

- `task_id`、`slug`、难度（Easy/Medium/Hard）、中英文名/描述；
- `scoring_points`（自然语言评分点）和 `score_steps`（带分值的结构化步骤）；
- `generalization`：`unseen_object_3`、`human_1_note`、`human_4_note`；
- 5 个示例 episode/video（`episode_0052` 等），可用于可视化与数据对齐抽查。

32 个任务合计 **94 个评分步骤**。分值不是随意的，是四种固定模板：

| 步骤数 | 任务数 | 分值模板 | 结构含义 |
|---:|---:|---|---|
| 2 | 11 | **50 / 50** | 抓取 + 放置/操作，两半各占一半 |
| 3 | 14 | **30 / 30 / 40** | 前两步各 30，最后一步 40 |
| 4 | 5 | **25 / 25 / 25 / 25** | 四步等权 |
| 5 | 2 | **20 / 20 / 20 / 20 / 20** | 五步等权 |

几个直接可用的例子：

- **T01 HangCup（Easy，2 步）**：抓杯把 50 / 挂到杯架标记位 50；human_1 杯子向后，human_4 杯子向右。
- **T26 PlugInEthernet（Medium，3 步）**：抓网线 30 / 扶网口 30 / 插入 40；human_1 把网线移开，human_4 把插口移开。
- **T09 ToolboxStorage（Hard，4 步）**：放两把工具 25 / 放完剩余工具 25 / 合盖 25 / 上锁 25；human_1 胶带向后，human_4 胶带向右。
- **T16 FoldTowel（Hard，5 步）**：铺平 20 / 上下对折 20 / 左折 20 / 右折 20 / 叠好放一边 20；human_1/4 都会把叠好的毛巾翻开。
- **T31 OrganizePencilCase（Medium，3 步）**：拉开拉链 30 / 放文具 30 / 拉上拉链 40；**没有 human 备注**。
- **T32 SyringeWaterTransfer（Medium，2 步）**：吸水 50 / 注水 50；**没有 human 备注**。

这张表改变了两件事：

1. **3 步任务的最后一步占 40%**，而它往往正是插入/挂/叠/合盖/拉拉链这些接触步骤；第 12 轮的「最后 3 厘米」正好压在 40% 上。
2. **2 步任务的第一步就是 50%**，而它往往就是抓取；抓错直接丢掉一半。4/5 步任务虽然等权，但抓取次数多，抓取可靠性会复合。

### 1.3 30/32 任务给了 human_1/human_4 备注；23/32 给了未见物品备注

官方备注不是泛泛的「人为干扰」，而是具体到「移动哪个物体、往哪个方向、在抓取前还是抓取后」：

| 扰动类型 | 代表任务 | 备注原文（节选） | 对方案的要求 |
|---|---|---|---|
| 抓取前平移目标 | T01/T02/T03/T06/T09/T10/T13/T15/T18/T20/T22/T23/T25/T28/T29/T30 | 杯子向后、水果向前、胶带向后、试管向右、手机向上 | 重定位目标/受器，更新抓取位姿 |
| 抓取后平移目标/受器 | T01/T02/T04/T08/T09/T10/T15/T18/T21/T23/T28/T29/T30 | 杯子向右、书向右、架子向左、外壳盖移开 | 跟随/重抓/更新放置目标 |
| 状态逆转 | T14/T16/T17/T19/T27/T29 | 瓶盖拧回、毛巾翻开、笔盒打开、拉链拉开、第二个碗拿走、外壳盖移开 | 后置条件检测 + 回滚到受影响步骤 |
| 目标被拿走 | T12 | 中途把锁拿走 | 重定位；找不到则优雅失败，保留步骤分 |
| 额外约束/初始条件改变 | T05/T10/T24 | 网线另一头也插上、插头拔起、可乐放回传送带起点 | 重新读任务语义，必要时 VLA 重规划 |
| 底座/受器移动 | T19/T25 | 包向左、放了第一个马上放第二个挪一下底座 | 重定位受器，更新相对目标 |
| 无备注 | T31/T32 | — | 未知扰动；保守处理，不针对性调参 |

**结论**：这 30 条备注是一套免费的「恢复测试集」。我们不需要猜 human 会怎么干扰；官方已经把类型和方向告诉我们了。T31/T32 没有备注，说明这两项的 human 轴可能不同或还没公开，不能把在 T01/T16 上调好的恢复策略直接当成对 T31/T32 有效。

- 41 个 feature；`FoldTowel` 的 `robot_type` 是 `unitree_g1_8520`，其余是 `unitree_g1`；跨任务微调时要注意这个差异。

### 1.5 官方 WLA：6B、24GB、LoRA，步骤条件化微调可行

- **UnifoLM-WLA-1.0**：6B 参数，约 2,500 小时真机数据，64 个任务，默认 `chunk_size=30`、`target_fps=30`；统一动作 54 维、状态 60 维；微调时冻结 VLM，只训 DiT action head + robot-state projector，单张 **24GB** GPU 可跑。
- 2026-09-29 仓库加入 **LoRA 微调**支持；这意味着我们可以在不重训 6B 的前提下，把「步骤描述」和「任务导向抓取」注入 action head。
- 挑战赛 API 的动作是 2×6 EE + 2×1 gripper + 7 pivot = **21 维**，需要从 WLA 54 维适配；这一步在第 12 轮已经做过接口分析，本轮继续沿用。

**战略结论**：不要再从零训 6B/14B。把官方 WLA 当唯一底座，把省下的算力投到**步骤条件化、抓取先验、安全恢复、单任务评测**。

### 1.6 近期工作：分层/抓取/安全都热，但没人把三者做成「官方任务图 + 单模型合规」的组合

- **分层规划**：H-VLA（arXiv 2609.22895）用 key-action model + motion planning；SPR（2603.09292）用空间子目标 + rewind；FineART（2609.36416）预测下一个子任务并做 subtask 中训练；HINT（2609.02653）只在子任务切换时做语义推理；LAW（2610.23334）用 VLM-WAM 做语义子任务进度；BATON（2608.16889）研究长程子任务切换的 handoff 条件。这些工作都在**学**一个高层规划器；我们的高层规划是官方给的，不学。
- **抓取位姿**：GraspLDP（2602.22862）把抓取先验注入扩散策略；TGrasp6D（2610.20901）用 VLM 任务先验 + 6DoF 精化；DynaMOMA（2606.25295）做动态抓取位姿；DemoGrasp（2509.22149）从单演示做通用灵巧抓取；CeDiRNet-6DoF（2609.31452）做布料 6DoF 抓取。这些工作说明「任务先验 + 抓取位姿」是 2026 年的前沿；我们的差异是用**33k 成功演示 + 官方步骤标签**直接挖任务导向先验，不训通用 6D 检测器。
- **安全**：AEGIS/VLSA（2512.11891v2，IROS 2026）用控制屏障函数做 plug-and-play 安全层；SafeStage（2609.21223）把安全拆成 before/during/after；VLA safety survey（2604.23775）系统梳理风险。这些工作说明「确定性安全层」是合规且有效的；我们的差异是把安全接到**官方步骤后置条件**和**human_1/human_4 扰动类型**上，而不是泛泛的碰撞 avoidance。
- **恢复**：OneTwoVLA（2505.11917）做自适应推理与错误检测/恢复；RePO-VLA（2605.09410）用 progress-aware value 做 recovery-driven optimization；SimpleMemVLA（2609.05533）做原生视频记忆长程；ChronoGraph（2609.39665）做功能 4D 场景图。这些工作提供组件，但没有人把它们和「官方 94 步评分图」对齐。

**我们的生态位**：不是再提一个「更大的分层 VLA」，而是**benchmark-native**：官方步骤图是免费的完美高层计划；33k 成功演示是免费的任务导向抓取先验；human 备注是免费的恢复测试集。把这三件免费资产用足，比再训一个高层 planner 更划算，也更合规。

### 1.7 为什么现在能做

- 官方 `tasks_v2` JSON 第一次把 94 个步骤、分值、human 备注公开；这是本轮最重要的新数据。
- 33k 成功演示、5 条同义指令、30Hz EE 位姿、夹爪开合事件：足够挖抓取先验，不需要额外标注。
- 官方 WLA + 24GB 微调 + LoRA：步骤条件化和辅助头可落地。
- 单任务不计分通道：可以在不烧正式提交的情况下做 A/B。
- 第 10–12 轮已经打好观测/接触/伺服的地基；本轮只补入口和出口。

## 2. 诊断：三道门，不是一道 3 厘米

把一次 180 秒的运行拆开：

```text
入口门（0–20% 时间）        中间门（20–80% 时间）           出口门（80–100% 时间）
抓对部位了吗？              最后 3 厘米对准了吗？            做完了吗？被人改了吗？
抓杯把/网线/拉链头/盒盖     插入/挂/叠/合盖/拉拉链            后置条件验证/回滚/重做
      │                           │                              │
      ▼                           ▼                              ▼
  抓错 → 后面全废            偏 2mm → 接触失败              状态被逆转 → 白做
```

第 12 轮的 CHUNK-SERVO 修的是中间门；本轮补的是入口门和出口门。三道门是串联的：入口失败，中间和出口都无从谈起；出口不验证，中间做得再好也可能被一次 human 扰动清零。

### 2.1 抓取是长程任务的复利

设一个任务需要 k 次抓取，单次抓取成功率 p，其他步骤理想化，则任务成功率近似 `p^k`：

| p \ k | 2 | 3 | 4 | 5 |
|---:|---:|---:|---:|---:|
| 0.80 | 0.64 | 0.51 | 0.41 | 0.33 |
| 0.85 | 0.72 | 0.61 | 0.52 | 0.44 |
| 0.90 | 0.81 | 0.73 | 0.66 | 0.59 |
| 0.95 | 0.90 | 0.86 | 0.81 | 0.77 |

这张表是**示意模型**，不是实测；但它说明一个方向：在 4 次抓取的任务上，把单次抓取从 0.85 提到 0.95，任务成功率从 0.52 提到 0.81（+29pp）。这比在最后 3 厘米上再调 1mm 的杠杆大得多。

官方任务结构正好放大了这个效应：

- **11 个 2 步任务**：第一步 50% 往往就是抓取；抓错直接丢一半。
- **14 个 3 步任务**：前两步各 30%，其中至少一步是抓取；最后一步 40% 往往是放置/插入/合盖。
- **5 个 4 步任务 + 2 个 5 步任务**：抓取次数 2–5 次，等权；抓取可靠性复合。
- 按官方步骤文本关键词统计，**25/32 任务显式出现抓/拿/扶/拧/拉/合/开/锁等操作动词**（94 步里 46 步）；按任务语义，几乎 **32/32** 都需要至少一次抓取或夹持（如 T06/T20/T21/T25/T27 的 "place/stack" 也隐含抓取，T32 的 "draw water" 需要先抓注射器）。这不是「少数任务的特例」，是主战场。

所以本轮把**抓取位姿估计**从「感知附属品」提升为「与伺服并列的一等公民」。

### 2.2 高层计划是免费的，不要再学一遍

官方 94 个步骤就是一份**完美的、带分值的、人工标注的高层计划**。再训一个 VLM/LLM planner 有三个问题：

1. **它要学的东西官方已经给了**：32 个任务、94 步、步骤顺序、分值、human 备注；从零学是浪费。
2. **它会引入第二个模型**：单模型规则下，独立 planner 的合规风险高；即使做成同一 checkpoint 的 head，也需要额外标注和训练。
3. **它会增加延迟**：高层推理在远程 API 下是稀缺资源；把延迟花在「重新发现官方步骤」上不划算。

所以本轮的「分层规划」是**模板化分层**，不是学习式分层：

```text
官方步骤图（给定） → 步骤条件化 VLA（执行） → 确定性监控器（推进/回滚）
```

VLA 的 prompt 不再是整段任务描述，而是 `当前步骤描述 + 目标物体/部位 + 受器`。这有三个好处：

- **短 prompt**：比整段任务描述更聚焦，减少语义歧义。
- **可验证**：每一步有后置条件，监控器可以判断「这一步做完没有」。
- **可回滚**：人把状态逆转时，知道回到哪一步，而不是整段重来。

### 2.3 人为干扰不是噪声，是 20% 的测试轴

官方规则：5 类泛化各 2 次，共 10 次/任务；human 轴占 **20%**。30/32 任务给了具体备注：

- 大多数是**平移**：抓取前/后移动目标或受器；重定位 + 更新相对目标就能救。
- 少数是**状态逆转**：T14 拧回瓶盖、T16 翻开毛巾、T17 打开笔盒、T19 拉开拉链、T27 拿走第二个碗、T29 移开外壳盖；必须检测后置条件并回滚。
- 极少数是**拿走/额外约束**：T12 把锁拿走、T05 把网线另一头也插上、T24 把食物放回传送带起点；需要重定位/重读语义/等待，不能硬套「重抓」。
- T31/T32 没有备注：未知，保守处理。

**结论**：恢复不是「加一个安全急停」，而是「知道自己在第几步、这一步的后置条件是什么、被破坏后回到哪一步」。这是任务级的安全，不是关节级的安全。

## 3. 方法：H-GRASP 四层

### 3.1 总架构

```text
                    ┌──────────────────────────────────────────────┐
                    │ Evaluator (N ports 8765..8765+N-1)           │
                    └───────────────────┬──────────────────────────┘
                                        │ websocket: obs / action chunk
                                        ▼
                    ┌──────────────────────────────────────────────┐
                    │ Per-port PolicyService (CPU)                  │
                    │                                              │
                    │ L3 任务层（1–5Hz，事件驱动）                  │
                    │   official 94-step graph                     │
                    │   step prompt + progress monitor + rollback  │
                    │        │ s_k, pre/post                       │
                    │        ▼                                     │
                    │ L2 抓取层（5–10Hz）                           │
                    │   task-oriented grasp prior                  │
                    │   retrieval + geometric proposals + scoring  │
                    │   pre-grasp servo + grasp verify             │
                    │        │ g*, T_pre                           │
                    │        ▼                                     │
                    │ L1 执行层（30Hz，5-step chunk）               │
                    │   CHUNK-SERVO: 30-step VLA plan              │
                    │   + 5-step visual servo + GEO-RESIDUAL       │
                    │        │ a_cmd                               │
                    │        ▼                                     │
                    │ L0 安全层（每 chunk）                         │
                    │   QP/CBF filter + collision/workspace/human  │
                    │   + irreversible-action gating               │
                    └───────────────────┬──────────────────────────┘
                                        │ async, batched
                                        ▼
                    ┌──────────────────────────────────────────────┐
                    │ Shared VLA server (GPU)                       │
                    │ UnifoLM-WLA-1.0 + step-conditioned head       │
                    │ (optional: grasp head, step head; same ckpt)  │
                    └──────────────────────────────────────────────┘
```

- **唯一学习模型**：VLA（官方 WLA 微调 action head；可选同 checkpoint 的抓取头/步骤头）。
- **确定性控制器**：任务图、抓取评分、视觉伺服、安全滤波、恢复状态机；无学习权重，不违反单模型。
- **数据资产**：33k 成功演示 → 抓取先验库 + 步骤分割标签 + 扰动合成；不是第二个模型，是检索索引/辅助标签。
- **数字孪生**：只做安全滤波/恢复/延迟的风洞，不训 6B 策略。

### 3.2 官方步骤图：从 94 个文本步骤到可执行任务图

对每个任务，解析 `score_steps` 为：

```text
G = (V, E)
V[k] = {
  id, zh, en,
  score,                     # 官方分值：50/50, 30/30/40, 25×4, 20×5
  desc,                      # 官方英文/中文描述
  pre:  [conditions],        # 前置：物体可见、夹爪空、目标未完成…
  post: [conditions],        # 后置：抓住、放到、插入、合盖、拉链闭合…
  grasp: {target, part, type} | null,   # 抓什么部位
  place: {target, receptacle} | null,   # 放到哪里
  irreversible: bool,        # 倒水/上锁/拉拉链/合盖/注水…
  retry: max_retries,
  timeout_s
}
E = 线性链（k → k+1）；重复步骤（多个水果/工具/试管）展开为同构子步骤
```

关键设计：

- **步骤描述直接来自官方**，不重新生成；中文/英文都保留，训练时做同义改写。
- **前置/后置条件由我们补**，但尽量用可观测的量：夹爪开合、EE 位姿、目标相对位姿、GEO-RESIDUAL 的接触/编辑分数、视觉状态（拉链闭合/盖子合上/锁打开）。
- **不可逆标记**：倒水、注水、上锁、拉拉链、合盖、拧紧等；这些动作前要验证，动作后要复验；不确定时暂停重观测，不硬做。
- **重复步骤展开**：T02 两个水果、T13 三个试管、T15 四把工具、T17 三个文具、T27 三个碗；展开后每个子步骤有自己的后置条件，避免「做了两个但第三个失败」被当成整步失败。

步骤状态机：

```text
k = 0
loop:
  if post_k(obs) == True: k += 1; retries = 0; continue
  if k >= K: done
  if perturbation(obs, G[k]): k = rollback(obs, G); continue
  if retries > max: fail_gracefully(partial_score)
  execute_step(G[k]); retries += 1
```

### 3.3 步骤条件化 VLA

训练时，把每条演示按官方步骤分段，每段用 `G[k].desc`（+ 同义改写）作为语言条件；推理时用当前步骤描述，而不是整段任务描述。

- **输入**：四路 RGB + 双臂关节/EE + 夹爪 + 下身体 + 步骤语言。
- **输出**：30 步动作 chunk（WLA 54D → API 21D），由 CHUNK-SERVO 切成 5 步执行。
- **辅助头（可选，C3）**：步骤分类头（当前步骤 k）、步骤完成头（post_k 概率）、抓取头（下一抓取位姿）。它们和 action head 共享同一个 WLA backbone/checkpoint。
- **训练损失**：
  `L = L_action + λ1 L_step + λ2 L_progress + λ3 L_grasp + λ4 L_lang`
  - `L_action`：WLA 原有的 flow-matching/回归损失；
  - `L_step`：步骤分类交叉熵（94 类或任务内 K 类）；
  - `L_progress`：步骤完成 BCE；
  - `L_grasp`：抓取位姿回归（位置/旋转/宽度），只在有抓取标签的帧；
  - `L_lang`：同义改写的一致性/对比损失（可选）。
- **数据划分**：按 episode/session/物体/背景分组，相邻帧不跨 split；避免「同一段视频的相邻帧」泄漏。
- **算力**：冻结 VLM，只训 action head + 小头；24GB 可跑；LoRA 可选；先 1–2 张卡做消融，再扩。

### 3.4 推理循环（伪代码）

```python
def reset(port):
    task = parse_task(obs.language)          # 32 任务之一
    G = load_step_graph(task)                # 官方 94 步之一
    state[port] = {"k": 0, "retries": 0, "mode": "EXECUTE",
                   "grasp_cache": {}, "safety": SafetyState()}

def get_action(port, obs):
    st = state[port]; G = st["G"]; k = st["k"]

    # L3: 完成/扰动检查
    if post_condition(G[k], obs, st):
        st["k"] = min(k + 1, len(G) - 1); st["retries"] = 0
    if perturbation(G[k], obs, st):
        st["k"] = rollback_step(G, obs, st)
        st["mode"] = "RECOVER"

    # L2: 抓取层
    if G[k].grasp and gripper_empty(obs):
        g_star = select_grasp(obs, G[k], st["grasp_cache"])   # 检索+几何+评分
        a_nom = servo_to_pregrasp(g_star, obs)                 # 5-step chunk
    else:
        # L1: 步骤条件化 VLA + CHUNK-SERVO
        plan = vla_plan_async(obs, prompt=G[k].desc)           # 30-step, background
        a_nom = servo_chunk(plan, obs, G[k].place)             # 5-step

    # L0: 安全层
    a_safe = safety_filter(a_nom, obs, st["safety"])           # QP/CBF
    if a_safe is None:
        a_safe = hold_or_retreat(obs)
        st["mode"] = "RECOVER"

    return adapt_to_api(a_safe), {"k": st["k"], "mode": st["mode"]}
```

### 3.5 每端口隔离与延迟

- 每个端口独立的 `k`、抓取缓存、安全状态、重试计数；`reset()` 清空。
- VLA 规划在后台线程/共享 GPU 服务；`get_action` 返回 5 步 chunk，不被 30 步推理阻塞。
- 安全滤波/步骤监控在 CPU；单端口开销 < 5ms；N 端口可并行。
- 延迟预算：VLA 100–300ms（后台摊薄）；伺服 5 步 = 167ms；安全/监控 < 5ms；RTT 0–150ms；端到端 200–320ms。
- 如果 RTT > 100ms 或控制频率低，`H_c` 从 5 调到 8；如果 RTT 低且任务动态，调到 3。**chunk size 是提交前要扫的超参数。**

## 4. 抓取位姿估计：从 33k 次成功抓取里挖「任务导向先验」

### 4.1 为什么不做通用 6D 物体位姿/抓取网络

- **没有物体位姿标注**：33k 演示只有 EE 位姿、夹爪、图像；通用 6D 网络需要物体 CAD/位姿标签，成本高。
- **透明/反光/变形物体多**：杯子、网线、拉链、毛巾、塑料袋、注射器；6D 位姿在这些物体上不可靠。
- **任务兼容性比几何稳定性更重要**：抓杯把 vs 抓杯身、抓网线 vs 抓插头、抓拉链头 vs 抓布、抓盒盖 vs 抓盒身；通用抓取检测器只给「能抓」，不给「该抓哪」。
- **单模型合规**：独立的 6D 抓取网络是第二个学习模型，风险高。

所以做**任务导向的演示抓取先验**：从成功演示里学「这个任务、这个步骤、这个部位，手应该在哪里」，再用几何评分保证稳定/可达/无碰撞。

### 4.2 离线挖取抓取位姿

对每条成功演示：

1. **步骤分段**：用官方 K 个步骤 + 夹爪开合事件 + 物体运动，把 episode 分成 K 段；重复步骤按抓取次数展开。人工抽查 5 条/task，确认边界。
2. **抓取时刻**：夹爪从 open（≈5.5）到 close（≈0）的闭合时刻；取闭合前 1–2 帧的 EE 位姿作为抓取位姿。
3. **记录**：
   - `T_base_ee`（EE 6D，base 系）；
   - `T_base_obj`（目标/受器 6D；刚体用头双目 + ICP/点云；透明/变形用 ROI + 腕部图）；
   - `T_obj_ee* = T_base_obj^-1 · T_base_ee`（相对抓取位姿）；
   - 腕部/头部 crop、视觉描述子、任务 ID、步骤 ID、夹爪宽度、接近方向；
   - 成功标记（演示本身是成功；失败/重试帧要过滤）。
4. **聚类/去重**：按 task/step/object/approach 聚类；每类保留 top-K 个几何多样、成功的抓取；记录成功率/覆盖率。
5. **规模估计**：33k episodes × 1–5 次抓取 ≈ 50k–100k 条抓取记录；足够检索和小头训练。

关键：**相对位姿 `T_obj_ee*` 是位置/背景/受器平移的不变量**。这正好对抗位置泛化和 human 平移扰动。

### 4.3 在线抓取选择

```text
输入：obs（四路 RGB + EE + 夹爪）、当前步骤 G[k]（抓什么部位/放哪里）
1. 定位目标/受器：
   - 刚体：头双目点云 + ROI + ICP/分割，得到 T_base_obj；
   - 透明/变形：腕部 ROI + 颜色/边缘/关键点，得到局部 2D 目标；
2. 候选生成：
   a. 演示检索：按 task/step/视觉描述子取 top-M 个 T_obj_ee*，
      变换到当前帧：T_base_ee^cand = T_base_obj^current · T_obj_ee*；
   b. 几何候选：在 ROI 点云上采反平行抓取，过滤夹爪宽度 5.5–0.0、接近方向、工作空间；
   c. 可选（C3）：VLA 抓取头直接出 K 个候选；
3. 评分：
   S(g) = w_t·C_task + w_s·Q_stab + w_r·R_ik
          + w_c·(1 - C_coll) + w_v·V + w_h·H
   - C_task：任务兼容（杯把/网线/拉链头/盒盖；抓取轴 vs 部位法向；与步骤语义一致）
   - Q_stab：反平行/力闭合、摩擦锥、宽度余量、接触面积
   - R_ik：IK 可达、关节余量、可操作性
   - C_coll：桌面/物体/自碰撞；点云/胶囊
   - V：可见性/遮挡；腕部能看到抓取点；双目深度有效
   - H：人/障碍物距离；风险感知裕度
4. 选择 g* = argmax S(g)；
   若 top-2 分数接近或最高分 < 阈值：先重观测/换视角，或回退到演示 top-1；
5. 预抓取 T_pre = T_g* · exp(-d·approach_axis)；
   接近 → 闭合 → 抬起 → 验证；
6. 验证：夹爪实际宽度 vs 指令；物体是否随 EE 运动（GEO-RESIDUAL r_grasp）；
   若滑移/未抓住：重抓（最多 2 次），否则回退 VLA。
```

### 4.4 可选：同一 checkpoint 的抓取头（C3）

如果组织方确认「同一模型的多头」没问题，可以在 WLA 上加一个小抓取头：

- 输入：VLM/action head 的中间特征 + 当前步骤 embedding；
- 输出：K 个抓取候选（位置 3 + 旋转 6D/四元数 4 + 宽度 1 + 置信度 1）；
- 训练：用 §4.2 的抓取标签做回归/分类；只在抓取帧算损失；
- 共享 backbone/checkpoint；不加载第二个模型；
- 推理时抓取头只做候选生成，最终仍由几何评分/安全层 veto。

**合规阶梯**：

| 模式 | 做法 | 合规风险 | 建议 |
|---|---|---|---|
| **C1** | 抓取标签只用于离线分析/微调 action head | 最低 | 保底 |
| **C2** | 演示检索 + 几何评分 + 确定性伺服，无学习抓取头 | 低 | **默认主路径** |
| **C3** | 同一 checkpoint 加抓取头/步骤头 | 中（需确认多头解释） | 冲分路径 |

本轮默认走 **C2**；C3 作为消融/冲分，不把合规押在「多头算不算一个模型」的解释上。

### 4.5 为什么这比通用抓取网络更适合本赛题

| 维度 | 通用 6D 抓取网络 | 任务导向演示先验 |
|---|---|---|
| 监督 | 需要物体位姿/抓取标注 | 33k 成功演示自带 |
| 任务语义 | 无（只给「能抓」） | 官方步骤给「该抓哪」 |
| 透明/变形 | 6D 位姿不可靠 | 腕部 ROI + 相对位姿 |
| 位置/背景泛化 | 依赖训练分布 | 相对位姿不变 |
| 合规 | 第二个模型 | 确定性检索/几何（C2） |
| 可解释 | 低 | 评分项可解释/可 veto |

## 5. 安全与恢复：把 human_1/human_4 当测试集，而不是当噪声

### 5.1 物理安全：QP/CBF 滤波，不做「急停开关」

每个 5 步 chunk 执行前，对名义动作 `a_nom` 做一次安全投影：

```text
a_safe = argmin_a  ||a - a_nom||²_Q + λ||a - a_prev||²_R
         s.t.      joint_limits(a) ≤ 0
                   velocity_limits(a) ≤ 0
                   workspace(a) ≤ 0
                   self_collision(a) ≥ d_min
                   table_clearance(a) ≥ d_min
                   human_clearance(a) ≥ d_human
                   grasp_stability(a) ≥ 0   (夹爪闭合时)
```

- **CBF 形式**：`h(x) ≥ 0`，`ḣ + αh ≥ 0`；离散时间检查 `h(x_{t+1}) ≥ (1-α)h(x_t)`。
- **不可行时**：保持/减速/沿接近轴后退；触发恢复；不硬执行。
- **风险感知裕度**：人/不可逆动作附近加大裕度；自由空间运输用小裕度；避免「安全滤波过度保守 → 成功率下降」。
- **人检测**：深度 blob/背景差分 + 本体感知；不加载第二个人体检测模型；不确定时用保守裕度，不声称 100%。

### 5.2 任务安全：后置条件 + 回滚

每个步骤定义可观测的后置条件：

| 步骤类型 | 后置条件 | 观测 |
|---|---|---|
| 抓取 | 夹爪闭合 + 物体随 EE 运动 | 夹爪宽度、`r_grasp`、物体相对位姿 |
| 放置 | 物体在目标位 + 稳定 | 目标相对位姿、N 帧静止 |
| 挂/插入 | 目标进入受器 + 不再需要支撑 | 相对位姿、视觉接触 |
| 拉拉链/合盖/上锁 | 状态变量改变 | 视觉状态（闭合/锁上） |
| 倒水/注水 | 液体转移 | 视觉液位/流量代理 |
| 铺平/折叠 | 形状/轮廓改变 | 视觉轮廓/关键点 |

监控器在 5 步边界检查：

```text
if not post_k(obs) and elapsed > timeout_k:
    if retries < max_retries:
        retry_step(k)
    else:
        k = rollback_step(G, obs)   # 找最早被破坏的后置条件
elif post_j(obs) == False for some j < k:
    k = j                           # 状态被逆转
else:
    k += 1
```

### 5.3 恢复策略树

```text
扰动检测（GEO-RESIDUAL + 后置条件 + 目标位姿突变）
├─ 抓取前目标/受器平移
│   → 重定位 T_base_obj；更新 T_base_ee^d；保守增益恢复伺服
├─ 抓取后物体平移/受器平移
│   ├─ 仍抓住 → 跟随/更新放置目标
│   └─ 滑移/掉落 → 重抓（最多 2 次）
├─ 状态逆转（拉链拉开/毛巾翻开/笔盒打开/瓶盖拧回/碗拿走/外壳移开）
│   → 找最早被破坏的 post_j；k = j；重做该步
├─ 目标被拿走（T12 锁）
│   → 重定位；找不到 → 优雅失败，保留已得步骤分
├─ 额外约束（T05 网线另一头也插上/T10 插头被拔起/T24 食物回起点）
│   → 重读任务语义；VLA 重规划；等待/重抓
├─ 人进入工作空间
│   → 减速/暂停；人离开后恢复；不硬撞
└─ 超过重试/时间预算
    → 优雅失败；返回 hold；保留 partial score
```

几个具体例子：

- **T19 ZipUp human_4 拉上后再拉开**：监控器看到拉链状态从闭合变打开 → `post_2` 被破坏 → `k=1`（第二步）→ 重拉拉链。不要从头重做「铺平」。
- **T27 StackBowls human_4 拿走第二个碗**：监控器看到堆叠高度下降 → `post_2` 被破坏 → `k=1` → 重新叠第二个碗。
- **T16 FoldTowel human_1/4 翻开毛巾**：监控器看到毛巾轮廓从折叠变展开 → `post_1` 被破坏 → `k=0` → 重新铺平/折叠。
- **T12 Unlock human_4 把锁拿走**：监控器看到锁消失 → 重定位；找不到 → 优雅失败，保留「拿起锁/转钥匙」的步骤分。
- **T24 ConveyorSorting human_1 把食物放回起点**：监控器看到目标回到传送带起点 → 等待/重新抓取；不要追着已经离开工作空间的食物。

### 5.4 安全-恢复的取舍

安全层不是越保守越好：

- **过度急停**：每次检测到人就停，human 轴的 20% 可能变成 0；而且频繁启停会丢失接触/抓取状态。
- **过度激进**：碰撞/超限/把人手夹住，可能被判违规或损坏设备。
- **目标**：在硬安全约束下，最大化「步骤完成 + 可恢复」；不是最大化「静止」。

所以安全层用**风险感知裕度**：

- 人/不可逆动作/高速段：大裕度、低增益、先验证后执行；
- 自由空间/低速/远离人：小裕度、正常增益、允许 VLA 执行；
- 不确定时：先重观测/换视角，而不是直接失败。

## 6. 竞赛策略：94 个步骤就是 94 个得分点

### 6.1 算术

- 总分 `S = (1/32) Σ_t p_t`；`p_t` 是任务 t 的 10 次平均成功率。
- 320 trials 下，`p≈0.25` 的单次标准误约 `sqrt(0.25×0.75/320)=2.42pp`；配对设计会低一些，但**不要声称 +1–2pp 是结论**。
- 步骤分是 tie-break：成功率相同看总平均步骤分，再相同看更早提交。所以**步骤级得分**不是装饰，是排名规则的一部分。
- 3 步任务的最后一步 40% ×14 个任务 = **5.6 个任务当量**；2 步任务的第一步 50% ×11 个任务 = **5.5 个任务当量**；4/5 步任务的抓取复合 = 7 个任务。三块加起来覆盖了大部分分数。
- human 轴 20%；如果恢复把 human 轴从 `p_h` 提到 `p_h+Δh`，全局约 `+0.2Δh`。若 `Δh=15pp`，全局 +3pp；若 `Δh=30pp`，全局 +6pp。

### 6.2 任务组合（先验，待单任务通道更新）

| 档 | 任务特征 | 代表任务 | 主投 | 不投 |
|---|---|---|---|---|
| **A：2 步抓放** | 50/50；第一步抓取，第二步放置/挂/插/拉链 | HangCup、FruitCollection、PackDoll、OrganizeBookshelf、DisconnectEthernet、ZipUp、StorePaddle、ConveyorSorting、RemovePinnedNote、SyringeWaterTransfer、PourOutMedicine | 抓取先验 + 相对放置 + 恢复 | 复杂世界模型 |
| **B：3 步最后 40%** | 30/30/40；最后一步是接触/闭合 | PlugInEthernet、PlugCharger、Unlock、PaperCupStacking、StoreCups、StackBowls、ArrangePlates、PackPhone、OrganizePencilCase、ColorArrangement、FruitSorting、PlacePhotoFrame、PickOutBatteries、ArrangeTestTubes、SpellRobot | 伺服 + 步骤条件化 + 不可逆门控 | 只堆语义数据 |

### 6.3 单任务通道协议（不计分，但决定是否烧正式提交）

1. 选 6 个代表任务：
   - HangCup（2 步抓+挂）；
   - PlugInEthernet（3 步插入，最后 40%）；
   - ZipUp（2 步拉链，不可逆状态）；
   - StackBowls（3 步叠放，human_4 拿走第二个）；
   - FoldTowel（5 步变形，human_1/4 翻开）；
   - ToolboxStorage（4 步长程，合盖/上锁）。
2. 每个任务 5 次 A/B：baseline（WLA + API 适配 + chunk 5）vs H-GRASP（步骤图 + 抓取先验 + 安全恢复）；同一初始条件；记录成功率、步骤分、首次抓取成功率、恢复率、p99 延迟、安全违规。
3. 通过标准：至少 4/6 任务 +10pp 步骤分或成功率；FoldTowel 不回归 >5pp；安全违规不增加；p99 不超预算。
4. 再扫 `H_c ∈ {3,5,8}`、抓取候选数 M、评分权重；选稳定折中。
5. 最后才跑 32×10 正式评测。

### 6.4 提交节奏

- 若允许多次提交：先交**安全基线**（官方 WLA + API 适配 + chunk 5/30 + 基本安全限幅），锁定「更早提交」tie-break；再交 H-GRASP。
- 若只允许一次：先在单任务通道把 H-GRASP 打磨到稳定，再交最终版。
- 不要把 320 trials 浪费在「从零训 6B」「完整世界模型」「32 个任务各训一个策略」上；这些不是本轮的最优边际收益。
- 不要追预览榜单的 29.7%；它不是实时结果，不能作为调参目标。

## 7. 与第 10–12 轮的关系：保留、升级、剪枝

**保留**：

- FACT-VLA 的相位化 BC、CAC 柔顺执行、EGP 证据门控；
- GEO-RESIDUAL 的动作条件化残差、米制表面距离、编辑检测；

- 官方 WLA 基座、33k 演示、官方 rubric、单任务通道。

**升级**：

- 手工/自动相位 → **官方 94 步任务图**：相位不再靠猜，直接来自 `score_steps`；
- 整任务语言条件 → **步骤条件化**：prompt 更短、更可验证、可回滚；
- 接触/编辑检测 → **抓取验证 + 放置验证 + 扰动检测**：GEO-RESIDUAL 从「标注」变成「控制信号」；
- 演示检索相对目标 → **任务导向抓取先验**：从「目标-夹爪相对位姿」扩展到「抓取-物体相对位姿」；
- 安全急停 → **安全-恢复包络**：物理安全 + 任务安全 + 可恢复性；
- 单个大模型 → **一个学习模型 + 确定性任务图/抓取评分/安全滤波**（合规）。

**剪枝**：

- 不做完整在线世界模型（太重、第二模型、延迟；离线只做数据引擎）；
- 不做通用 6D 物体位姿网络（透明/变形不可靠；用相对位姿 + ROI）；
- 不做独立 VLM/LLM planner（官方步骤图已给；合规/延迟不划算）；
- 不做学习残差策略（单模型风险；用确定性伺服/滤波）；
- 不做 32 个任务各一个策略（规则禁止，且不泛化）；
- 不做 30Hz 广域网伺服（RTT 不允许；用 5 步 chunk/双频）；
- 不做从零训 6B/14B（官方 WLA 已做完）；
- 不做完整 sim-to-real 策略训练（只做安全/恢复/延迟风洞）；
- 不做力/触觉闭环（API 没有）；
- 不把预览榜单任务排名当难度表（已证伪）；
- 不把 T31/T32 的 human 轴当成已知（没有备注）。

**明确不建议继续投**：从零训通用 VLA/World Model、完整 sim-to-real 策略训练、30Hz 广域网视觉伺服、逐任务学习策略、通用 6D 物体位姿网络、独立高层 planner、力/触觉闭环。这些方向要么已被官方 WLA 覆盖，要么被规则/接口/延迟/数据限制，边际收益低于「入口抓取 + 出口恢复 + 官方步骤图」。

## 9. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被抓取头/步骤头判为第二个模型 | 默认 C2（检索+几何+确定性滤波）；C3 只在确认后使用；提交材料写清楚「一个 checkpoint，多头共享 backbone」 |

| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组；相邻帧不跨 split |
| 预览榜单误导 | 调参目标错误 | 不把 29.7% 当 SOTA；以官方步骤分/单任务通道为准 |
| 时间/算力 | 做不完 | 先 C2 抓取 + 步骤图 + 基本安全；C3/高级恢复后置 |
| T31/T32 无 human 备注 | 恢复策略不匹配 | 保守处理；不针对性调参；单独观察 |

这些数字是**算术上的上限估计**，不是实测；必须用配对 A/B 和单任务通道验证。320 trials 下 `p≈0.25` 的单次标准误约 2.42pp，不要声称 +1–2pp 是结论。

## 2. 问题形式化

### 2.1 任务与步骤图

一个任务 `T = (L, G, I)`：

- `L`：语言指令（5 条同义改写之一）；
- `G = (V, E)`：官方步骤图；
- `I`：初始状态/场景。

步骤节点：

```text
V[k] = {
  id, zh, en,
  score,                 # 官方分值
  desc,                  # 官方描述
  pre:  [conditions],    # 前置条件
  post: [conditions],    # 后置条件
  grasp: {target, part, type} | null,
  place: {target, receptacle} | null,
  irreversible: bool,
  retry_max, timeout_s
}
E = {(k, k+1)}  # 线性链；重复步骤展开
```

任务得分：

```text
S_task = Σ_{k=0}^{K-1} s_k · 1[post_k 在预算内完成]
success = 1[所有 post_k 完成]
```

排名规则：先平均成功率，再平均步骤分，再更早提交。所以**部分完成也有价值**；步骤图不仅服务成功，也服务 tie-break。

### 2.2 策略

带步骤条件的策略：

```text
π_θ(a_{t:t+H_c} | o_t, s_k, L)
```

- `o_t`：四路 RGB + 双臂关节/EE + 夹爪 + 下身体；
- `s_k`：当前步骤描述/目标/受器；
- `H_c`：执行 chunk（默认 5；可扫 3/5/8）；
- 30 步 VLA plan 在后台生成，5 步 servo 执行；chunk 内开环。

与整任务条件 `π(a | o, L)` 相比，步骤条件把「从整段任务里自己找当前该做什么」变成「给定这一步，输出动作」，降低语义歧义和长程漂移。

### 2.3 抓取位姿

抓取位姿：

```text
g = (p ∈ R³, R ∈ SO(3), w ∈ [0, 5.5])
```

其中 `w` 是 Dex1 夹爪宽度（5.5 开 → 0 闭）。相对抓取位姿：

```text
T_obj_ee* = T_base_obj^{-1} · T_base_ee
```

在线候选：

```text
T_base_ee^cand = T_base_obj^current · T_obj_ee*
```

评分：

```text
S(g) = w_t·C_task(g) + w_s·Q_stab(g) + w_r·R_ik(g)
       + w_c·(1 - C_coll(g)) + w_v·V(g) + w_h·H(g)
```

选择 `g* = argmax S(g)`，并检查 top-2 margin；低置信度时重观测/回退。

### 2.4 安全与恢复

名义动作 `a_nom` 的安全投影：

```text
a_safe = argmin_a ||a - a_nom||²_Q + λ||a - a_prev||²_R
         s.t.     h_i(x, a) ≥ 0,  i = 1..m
```

其中 `h_i` 包括关节限位、速度限位、工作空间、自碰撞、桌面间隙、人距、夹爪闭合时的抓取稳定性。

CBF 形式：

```text
h_i(x_{t+1}) ≥ (1 - α_i) h_i(x_t),  α_i ∈ (0, 1]
```

不可行时：保持/减速/沿接近轴后退；触发恢复；不硬执行。

恢复算子：

```text
rollback(G, o) = min{ j : post_j(o) == False }
```

即回到最早被破坏的后置条件，而不是整段重来。

### 2.5 为什么官方步骤图是免费的完美高层计划

- 官方给了 32 任务、94 步、顺序、分值、human 备注；高层计划不需要学。
- 需要学的是 **grounding + execution + recovery**：
  - `p(grasp | o, s_k)`：这一步抓哪里；
  - `p(a | o, s_k, g*)`：怎么对准/放置；
  - `p(post_k | o)`：这一步做完没有；
  - `p(perturbation | o, s_k)`：场景是否被改动。
- 这把一个长程规划问题拆成「步骤分类 + 抓取选择 + 短程控制 + 状态验证」四个小问题，每个都可以用确定性方法或小头解决。

### 3.3 步骤条件化 VLA

**Prompt 模板**：

```text

目标：{grasp.target} / {place.receptacle}
约束：{irreversible ? "先验证再执行" : ""}
```

- 训练时用官方英文/中文描述 + 5 条同义改写（来自 `meta/tasks.parquet`）+ 模板化改写（同义动词/目标别名）。
- 推理时用当前步骤描述，不用整段任务描述；整段任务描述作为 fallback（当步骤解析失败或需要重规划时）。
- 语言条件与视觉/本体特征一起进 WLA；冻结 VLM，只训 action head + 小头。

**动作适配**：

```text
WLA 54D:
  left/right EE 6 (relative xyz + rotvec in current EE frame)
  left/right gripper 1
  left/right dexterous hand 6
  waist 3, torso 3, base 2 + yaw 1, base pose 6, left/right leg 6
挑战赛 21D:
  left/right EE 6 (absolute xyz + rpy in base frame)
  left/right gripper 1

```

适配要点：

- WLA 的相对 EE 动作 → 积分成绝对目标 → 转 base 系 rpy；或用 API 的 `ee` 控制模式直接发绝对目标。
- 夹爪 1 通道映射到 Dex1 的 5.5–0.0；不要用五指手的 6 维。
- `pivot` 7 维在桌面任务里保持默认/零，除非任务需要底座移动（T24 传送带、T25 挪底座）。
- `action_chunk_size` 默认 5；如果 API 要求固定 30，则在内部把 30 步 plan 切成 6 个 5 步块，但 evaluator 仍会执行 30 步——这时要确认 evaluator 是否允许 chunk 内多次 `get_action`。**这是接口层必须先实测的点。**

**辅助头（可选，C3）**：

```text
shared WLA backbone
├─ action head (DiT) → 30-step action chunk
├─ step head → K-way step classification
├─ progress head → P(post_k)
└─ grasp head → K grasp candidates (p, R, w, confidence)
```

损失：

```text
L = L_action
  + λ1 L_step      (cross-entropy, 任务内 K 类)
  + λ2 L_progress  (BCE, post_k)
  + λ3 L_grasp     (position L2 + rotation geodesic + width L1, 仅抓取帧)
  + λ4 L_lang      (同义改写一致性, 可选)
```

数据划分：按 episode/session/物体/背景分组；相邻帧不跨 split；验证集按任务留出或按 episode 留出，避免泄漏。

### 3.4 抓取层

**离线挖取**：

```python
for episode in demos:
    steps = segment_steps(episode, K=len(task.score_steps))
    for k, seg in enumerate(steps):
        close_t = detect_gripper_close(seg)   # 5.5 → 0 的闭合时刻
        if close_t is None: continue
        T_ee = ee_pose(close_t - 1)           # 闭合前 1–2 帧
        T_obj = estimate_object_pose(seg[close_t - 2:close_t + 2], task, k)
        if T_obj is None: continue
        T_rel = inv(T_obj) @ T_ee
        store(task_id, k, T_rel, width=5.5, images=crops(...),
              descriptor=classical_descriptor(...))
```

- **夹爪闭合检测**：Dex1 位置从 ≈5.5 到 ≈0；用滞回阈值（<1.0 且持续 ≥2 帧）；闭合前 1–2 帧的 EE 位姿作为抓取位姿。
- **步骤分段**：官方 K 步 + 夹爪事件 + 物体运动；重复步骤按抓取次数展开；用 DTW 对齐；人工抽查 5 条/task。
- **物体位姿**：刚体用头双目点云 + ROI + ICP；透明/变形用 ROI + 腕部图 + 相对位姿；没有可靠 `T_obj` 时，退化为「EE 相对当前腕部 ROI」的局部先验。
- **过滤**：只取成功演示；过滤闭合后滑移/重试；按 task/step/object/approach 聚类去重；每类保留 top-K 多样抓取。
- **规模**：33k episodes × 1–5 次抓取 ≈ 50k–100k 条记录；足够检索和小头训练。

**数据 schema**：

| 字段 | 维度 | 说明 |
|---|---|---|
| `task_id` | 1 | T01–T32 |
| `step_id` | 1 | 任务内步骤 |
| `T_rel` | 4×4 | `T_obj_ee*`，相对抓取位姿 |
| `width` | 1 | 夹爪宽度（5.5–0.0） |
| `approach` | 3 | 接近方向（EE z 轴或局部法向） |
| `desc` | D | 经典视觉描述子（C2）或 VLA 特征（C3） |
| `crop_wrist` | H×W×3 | 腕部 ROI |
| `crop_head` | H×W×3 | 头部 ROI |

**在线选择**：

```python
def select_grasp(obs, step, cache):

    cands = []
    cands += retrieve_topM(step, obj, cache, M=8)      # T_obj_ee* → current

    if use_grasp_head:                                  # C3

    return scored[0][0]
```

**评分项**：

| 项 | 含义 | 计算 | 失败模式 |
|---|---|---|---|
| `C_task` | 任务兼容 | 抓取轴 vs 部位法向；部位类别（杯把/网线/拉链头/盒盖）；与步骤语义一致 | 抓杯身/抓布/抓盒盖 |
| `Q_stab` | 稳定 | 反平行、摩擦锥、宽度余量、接触面积 | 滑移/夹不紧 |
| `R_ik` | 可达 | IK 解、关节余量、可操作性 | 够不到/奇异 |
| `C_coll` | 碰撞 | 桌面/物体/自碰撞；点云/胶囊 | 撞杯/撞架/自碰 |
| `V` | 可见 | 腕部能看到抓取点；双目深度有效 | 遮挡/透明深度缺失 |
| `H` | 人距 | 到人/障碍物的距离；风险感知裕度 | 夹手/撞人 |

权重先验：`w_t=0.30, w_s=0.20, w_r=0.15, w_c=0.20, w_v=0.10, w_h=0.05`；用单任务通道/仿真扫。不要把这些权重当成普适常数。

**抓取执行**：

```text
T_pre = T_g * exp(-d_approach * approach_axis)
servo to T_pre (PBVS/IBVS, 5-step chunk, 限速)
approach along axis, close gripper (5.5 → 0), wait 2–3 frames
lift 2–3 cm
verify: gripper width vs command; object motion with EE (r_grasp)
if slip: re-grasp (max 2), else fallback to VLA
```

**验证信号**：

- 夹爪实际宽度：闭合后是否达到预期（空抓会过闭）。
- 物体随 EE 运动：GEO-RESIDUAL `r_grasp` 小 → 抓住；突变 → 滑移/掉落。
- 腕部图像：抓取点是否在夹爪之间；抓取后物体是否离开桌面。

### 3.5 安全层

**QP**：

```text
min_a  ||a - a_nom||²_Q + λ||a - a_prev||²_R
s.t.   q_min ≤ q(a) ≤ q_max
       |q̇(a)| ≤ q̇_max
       p_ee(a) ∈ W
       d_self(a) ≥ d_min
       d_table(a) ≥ d_min
       d_human(a) ≥ d_human
       grasp_stability(a) ≥ 0  (夹爪闭合时)
```

- 变量可以是关节位置/速度，也可以是 EE 目标；用 `ee` 控制时把 EE 目标映射到关节约束（IK/雅可比）。
- QP 规模小（< 20 维），CPU < 1ms；每 5 步 chunk 解一次。
- 不可行：保持/减速/沿接近轴后退；触发恢复；记录不可行原因。

**CBF**：

```text
h(x) ≥ 0
h(x_{t+1}) ≥ (1 - α) h(x_t)
```

- 对离散 chunk，用 `h` 的预测/保守近似；不要假设连续时间。
- 安全裕度按风险分层：

| 场景 | 人距裕度 | 速度 | 备注 |
|---|---|---|---|
| 自由空间运输 | 小 | 正常 | 不打断 VLA |
| 接近目标/接触 | 中 | 降速 | 允许微调 |
| 人在工作空间 | 大 | 降速/暂停 | 人离开后恢复 |
| 不可逆动作（倒水/上锁/拉拉链/合盖） | 大 | 慢 | 先验证再执行 |
| 夹爪闭合/抓取 | 中 | 慢 | 抓取稳定性约束 |

**人检测**：深度 blob/背景差分 + 本体感知；不加载第二个人体检测模型。检测到人 → 加大裕度/降速；不确定 → 保守但不硬停。

### 3.6 任务状态监控与恢复状态机

状态：

```text
EXECUTE → (post_k) → ADVANCE → EXECUTE
EXECUTE → (perturbation) → RECOVER → (rollback) → EXECUTE
EXECUTE → (timeout/retry exhausted) → FAIL_GRACEFUL
```

伪代码：

```python
def monitor(obs, G, st):
    k = st["k"]
    if post_condition(G[k], obs, st):
        st["k"] = min(k + 1, len(G) - 1)
        st["retries"] = 0
        return "ADVANCE"
    if perturbation(G[k], obs, st):
        st["k"] = rollback_step(G, obs, st)
        st["retries"] += 1
        return "RECOVER"
    if time_in_step(st) > G[k].timeout_s:
        if st["retries"] < G[k].retry_max:
            st["retries"] += 1
            return "RETRY"
        return "FAIL_GRACEFUL"
    return "EXECUTE"
```

**后置条件表**：

| 步骤类型 | 后置条件 | 观测信号 | 阈值/备注 |
|---|---|---|---|
| 抓取 | 夹爪闭合 + 物体随 EE | 夹爪宽度、`r_grasp`、物体相对位姿 | 宽度 < 1.0；`r_grasp` 小于基线 |
| 放置 | 物体在目标位 + 稳定 | 目标相对位姿、N 帧静止 | 位置 < 1–2cm；N=5–10 |
| 挂/插入 | 目标进入受器 + 保持 | 相对位姿、视觉接触 | 任务特定 |
| 拉拉链/合盖/上锁 | 状态变量改变 | 视觉状态 | 闭合/锁上/对齐 |
| 倒水/注水 | 液体转移 | 液位/流量代理 | 任务特定 |
| 铺平/折叠 | 形状/轮廓改变 | 轮廓/关键点 | 任务特定 |

**回滚算法**：

```python
def rollback_step(G, obs, st):
    for j in range(st["k"], -1, -1):
        if not post_condition(G[j], obs, st):
            return j
    return 0
```

**恢复树**：

```text
扰动检测（GEO-RESIDUAL + 后置条件 + 目标位姿突变）
├─ 抓取前目标/受器平移
│   → 重定位 T_base_obj；更新 T_base_ee^d；保守增益恢复伺服
├─ 抓取后物体平移/受器平移
│   ├─ 仍抓住 → 跟随/更新放置目标
│   └─ 滑移/掉落 → 重抓（最多 2 次）
├─ 状态逆转
│   → 找最早被破坏的 post_j；k = j；重做该步
├─ 目标被拿走
│   → 重定位；找不到 → 优雅失败，保留步骤分
├─ 额外约束
│   → 重读任务语义；VLA 重规划；等待/重抓
├─ 人进入工作空间
│   → 减速/暂停；人离开后恢复；不硬撞
└─ 超过重试/时间预算
    → 优雅失败；返回 hold；保留 partial score
```

**不可逆动作门控**：

| 动作 | 例子 | 执行前 | 执行后 |
|---|---|---|---|
| 倒水/注水 | T14, T32 | 目标杯对齐、瓶口/针头对准、抓稳 | 液位/流量验证；不对则停止 |
| 上锁 | T09 | 锁扣对齐、盖子闭合 | 锁上验证 |
| 拉拉链 | T18, T19, T23, T31 | 拉链头抓住、布面平 | 拉链闭合验证 |
| 合盖 | T09, T17, T28, T29 | 盖子对齐、无杂物 | 闭合验证 |
| 拧紧/拧开 | T14 | 瓶口/盖子对齐 | 状态验证 |

原则：**不确定就不做**；先重观测/换视角；宁可保留 partial score，也不要不可逆地做错。

### 3.7 每端口隔离与延迟

- 每端口独立：`k`、抓取缓存、安全状态、重试计数、时间预算；`reset()` 清空。
- VLA 规划在后台线程/共享 GPU 服务；`get_action` 返回 5 步 chunk，不被 30 步推理阻塞。
- 安全滤波/步骤监控在 CPU；单端口 < 5ms；N 端口可并行。
- 延迟预算：

| 项 | 预算 |
|---|---|
| VLA 推理 | 100–300ms（后台摊薄；1 次 plan 服务 6 个 5 步块） |
| 伺服 chunk | 5 步 @30Hz = 167ms |
| 安全/监控 | < 5ms |
| RTT | 0–150ms（提交前测） |
| 端到端 | 200–320ms（含 RTT） |

- 如果 RTT > 100ms 或控制频率低：`H_c` 从 5 调到 8；如果 RTT 低且任务动态：调到 3。
- 图片 payload：腕部 128×128、头部 240×320；4 路 JPEG 后约几十 KB/次。

### 3.8 数字孪生/仿真

不做「sim-to-real 训 6B 策略」。做三件事：

1. **标定**：G1 URDF + 头双目内参 + 腕部相机模型；拟合外参/焦距尺度/腕部安装误差；用真实演示 EE 位姿/重投影误差做最小二乘。
2. **调参**：在 MuJoCo/IsaacLab 搭 3 个任务族（peg-in-hole、hang/stack、zip/fold）；扫 `H_c`、伺服增益、QP 裕度、RTT；找稳定域，不找「最高成功率」。
3. **压测**：注入位置偏移、遮挡、背景变化、目标被移动/拿走、状态逆转、人手进入；测检测延迟、恢复率、超调、安全违规。

数字孪生是**控制器/安全层的风洞**，不是策略的训练场。这样 sim-to-real gap 只影响标定/调参，不影响策略分布。

## 4. 抓取位姿估计推导

### 4.1 坐标系与误差传播

坐标系：

- `b`：机器人 base；
- `e`：EE；
- `o`：目标/受器；
- `c`：相机（头/腕）。

相对抓取位姿：

```text
T_oe* = T_bo^{-1} T_be*
```

在线候选：

```text
T_be^cand = T_bo^current T_oe*
```

位置误差近似：

```text
δp_cand ≈ δp_o + R_o δp_rel + (∂/∂θ) ...
```

- 刚体：`δp_o` 来自双目/ICP，通常 2–5mm；`δp_rel` 来自演示聚类，1–3mm。
- 透明/变形：`T_bo` 不可靠，退化到腕部 ROI 的 2D 相对先验；此时用 IBVS 而不是 PBVS。
- 旋转误差：用 `log(R_cand^T R_des)` 或测地线距离；接近方向误差比位置误差更致命（抓偏轴 → 夹空）。

### 4.2 从演示挖抓取

**夹爪闭合事件**：

```text
Dex1 gripper position: 5.5 (open) → 0.0 (close)
close_t = first t such that g_t < 1.0 and g_{t+1} < 1.0
grasp_pose = ee_pose(close_t - 1)  # 闭合前 1–2 帧
```

- 用滞回：避免在 1.0 附近抖动；要求连续 2–3 帧。
- 如果夹爪从未闭合（极少数纯推动/放置步骤），跳过。
- 如果闭合后立即打开（空抓/试探），过滤。

**步骤分段**：

- 官方 K 步；用夹爪事件 + 物体运动 + DTW 对齐；
- 重复步骤（两个水果/三个试管/四把工具/三个文具/三个碗）按抓取次数展开；
- 人工抽查 5 条/task；边界误差 >2 帧的 episode 剔除或降权。

**过滤/聚类**：

- 只取成功演示；过滤滑移/重试/空抓；
- 按 task/step/object/approach 聚类；
- 每类保留 top-K 几何多样抓取；记录成功率/覆盖率；
- 对 `FoldTowel` 的 `robot_type=unitree_g1_8520` 单独处理，不与其他任务混聚类。

### 4.3 候选生成

**C2（默认，无学习抓取头）**：

1. **演示检索**：用经典描述子（颜色直方图、ORB、ROI 几何、边缘）在 task/step 内检索 top-M；把 `T_oe*` 变换到当前帧。
2. **几何候选**：在 ROI 点云/深度上采反平行抓取；过滤夹爪宽度（0–5.5）、接近方向、工作空间、桌面碰撞。
3. **任务过滤**：按步骤目标/部位过滤（杯把/网线/拉链头/盒盖/瓶盖）；用几何启发式（细长部位、把手、边缘）或人工部位框。

**C3（可选，同一 checkpoint 抓取头）**：

- 输入：VLM/action head 中间特征 + 步骤 embedding；
- 输出：K 个候选（p, R, w, confidence）；
- 训练：§4.2 的抓取标签；只在抓取帧算损失；
- 推理：候选生成后仍由几何评分/安全层 veto。

**注意**：C2 的检索描述子如果使用 DINOv2/CLIP 等独立视觉编码器，可能被解释为第二个模型；默认用经典描述子。C3 用 WLA 自身特征，合规性更好，但需要确认「多头」解释。

### 4.4 评分

```text
S(g) = w_t·C_task + w_s·Q_stab + w_r·R_ik
       + w_c·(1 - C_coll) + w_v·V + w_h·H
```

**C_task（任务兼容）**：

- 部位匹配：步骤说「杯把」→ 候选点必须在把手上；步骤说「网线」→ 候选点靠近插头；步骤说「拉链头」→ 候选点在拉链头。
- 抓取轴 vs 部位法向：夹爪闭合方向应垂直于把手/边缘的长轴；接近方向应沿法向。
- 间隙：夹爪张开 5.5 能否容纳部位；闭合后是否有余量。
- 语义：C3 可以用步骤 embedding 学习；C2 用规则/几何。

**Q_stab（稳定）**：

- 反平行：两接触点法向近似相反；
- 摩擦锥：`|f_t| ≤ μ f_n`；μ 先验 0.5–1.0；
- 宽度余量：`w_grasp ∈ [w_min + ε, 5.5 - ε]`；
- 接触面积：点云接触点数量/曲率。

**R_ik（可达）**：

- IK 解存在；关节余量 > 5–10°；可操作性 > 阈值；
- 预抓取位姿在 workspace 内；接近路径无碰撞。

**C_coll（碰撞）**：

- 桌面/物体/自碰撞；用点云/胶囊/包围盒；
- 预抓取/接近路径采样检查，不只检查终点。

**V（可见）**：

- 腕部相机能看到抓取点；
- 双目深度有效（透明/反光会缺失）；
- 遮挡：头/腕视角至少一路可见。

**H（人距）**：

- 到人/障碍物距离；风险感知裕度；
- 人在附近时提高 `w_h` 或直接 veto 高风险候选。

**选择**：

```text
g* = argmax S(g)
if S(g*) < τ_abs or S(g*) - S(g_2) < τ_margin:
    re-observe / change view / fallback to VLA
```

### 4.5 抓取执行与验证

```text
1. 预抓取：T_pre = T_g* · exp(-d·approach_axis)，d=5–10cm
2. 伺服到 T_pre：PBVS/IBVS，5 步 chunk，限速
3. 沿接近轴接近：接触段降速/法向缩幅
4. 闭合夹爪：5.5 → 0，等待 2–3 帧
5. 抬起 2–3cm
6. 验证：
   - 夹爪宽度是否达到预期（空抓会过闭）
   - 物体是否随 EE 运动（r_grasp）
   - 腕部图：物体是否在夹爪之间
7. 失败：重抓（最多 2 次）；仍失败 → 回退 VLA/换候选
```

### 4.6 可选抓取头（C3）

```text
输入：WLA 中间特征 + 步骤 embedding + ROI 特征
输出：K × (p 3, quat 4, width 1, confidence 1)
损失：position L2 + rotation geodesic + width L1 + confidence BCE
训练：冻结 VLM；只训 action head + 抓取头；24GB；LoRA 可选
推理：候选生成 → 几何评分 → 安全 veto
```

**合规阶梯**：

| 模式 | 做法 | 合规风险 | 建议 |
|---|---|---|---|
| **C1** | 抓取标签只用于离线分析/微调 action head | 最低 | 保底 |
| **C2** | 演示检索 + 几何评分 + 确定性伺服，无学习抓取头 | 低 | **默认主路径** |
| **C3** | 同一 checkpoint 加抓取头/步骤头 | 中（需确认多头解释） | 冲分路径 |

本轮默认走 **C2**；C3 作为消融/冲分，不把合规押在「多头算不算一个模型」的解释上。

### 4.7 相对位姿的鲁棒性与边界

**鲁棒**：

- 位置泛化：目标/受器平移 → `T_bo` 变，`T_oe*` 不变；
- 背景/干扰物：检索用局部 ROI，不用全局背景；
- 人为平移：重定位后相对位姿仍有效；
- 未见物品：只要受器/任务几何不变，抓取相对位姿可迁移；外观变化由 VLA/视觉描述子处理。

**边界**：

- 透明/反光/变形物体：`T_bo` 不可靠；退化到腕部 2D/IBVS；
- 严重遮挡：重观测/换视角；不要硬抓；
- 物体被拿走：重定位；找不到则优雅失败；
- 抓取部位语义错误（抓杯身）：C_task 规则/学习必须能 veto；这是抓取层最重要的失败模式。

## 5. 安全与恢复推导

### 5.1 QP/CBF

**QP**：

```text
min_a  ||a - a_nom||²_Q + λ||a - a_prev||²_R
s.t.   q_min ≤ q(a) ≤ q_max
       |q̇(a)| ≤ q̇_max
       p_ee(a) ∈ W
       d_self(a) ≥ d_min
       d_table(a) ≥ d_min
       d_human(a) ≥ d_human
       grasp_stability(a) ≥ 0
```

- `Q` 权重：位置/旋转/夹爪分别设；接触段降低位置权重、提高柔顺。
- `λ`：抑制 chunk 间抖动；RTT 高时增大。
- 约束用保守近似（点云/胶囊/包围盒）；不要用精确网格做在线 QP。

**CBF**：

```text
h_i(x) ≥ 0
h_i(x_{t+1}) ≥ (1 - α_i) h_i(x_t)
```

- `α_i` 越大，允许越快的恢复；接触/人附近取小 `α`（更保守）。
- 离散时间检查用预测/保守近似；不要假设连续时间可微。

**不可行处理**：

1. 保持当前位置；
2. 降速/缩小步长；
3. 沿接近轴后退 1–2cm；
4. 触发恢复/重观测；
5. 记录不可行约束，供离线调参。

### 5.2 无第二模型的人检测

- **深度 blob**：头双目深度 → 工作空间内的高于桌面的连通块；按高度/尺寸/运动筛选。
- **背景差分**：静态背景减去当前帧；检测进入工作空间的物体/手。
- **本体感知**：EE/关节电流/位置突变；夹爪受阻。
- **不确定时**：加大裕度/降速，不硬停；不声称 100% 检测。
- **不做**：加载独立人体检测/姿态模型（第二模型风险）。

### 5.3 任务状态监控

**后置条件**：

| 步骤类型 | 后置条件 | 观测 | 阈值/备注 |
|---|---|---|---|
| 抓取 | 夹爪闭合 + 物体随 EE | 夹爪宽度、`r_grasp`、相对位姿 | 宽度 <1.0；`r_grasp` 小于基线 |
| 放置 | 物体在目标位 + 稳定 | 相对位姿、N 帧静止 | 位置 <1–2cm；N=5–10 |
| 挂/插入 | 目标进入受器 + 保持 | 相对位姿、视觉接触 | 任务特定 |
| 拉拉链/合盖/上锁 | 状态变量改变 | 视觉状态 | 闭合/锁上/对齐 |
| 倒水/注水 | 液体转移 | 液位/流量代理 | 任务特定 |
| 铺平/折叠 | 形状/轮廓改变 | 轮廓/关键点 | 任务特定 |

**监控频率**：每 5 步 chunk 一次；关键步骤（插入/合盖/拉链）可以每 2–3 步一次。

**滞回/去抖**：连续 2–3 帧满足才推进；连续 2–3 帧不满足才回滚；避免单帧噪声。

### 5.4 扰动分类与响应

| 扰动 | 检测信号 | 响应 | 例子 |
|---|---|---|---|
| 抓取前目标平移 | 目标位姿突变；GEO-RESIDUAL | 重定位；更新抓取；保守增益 | T01 杯子向后 |
| 抓取后目标平移 | 物体相对位姿突变；`r_grasp` | 跟随/重抓；更新放置 | T01 杯子向右 |
| 受器平移 | 受器位姿突变 | 重定位；更新放置 | T21 架子向左 |
| 状态逆转 | 后置条件从真变假 | 回滚到最早被破坏步骤 | T19 拉链被拉开 |
| 目标被拿走 | 目标消失；匹配失败 | 重定位；找不到优雅失败 | T12 锁被拿走 |
| 额外约束 | 任务语义/场景变化 | 重读任务；VLA 重规划 | T05 网线另一头也插上 |
| 传送带重置 | 目标回到起点 | 等待/重抓 | T24 食物回起点 |
| 人进入工作空间 | 深度 blob/背景差分 | 降速/暂停；人离开恢复 | 所有 human 轴 |
| 夹爪滑移 | `r_grasp` 突变；宽度异常 | 重抓；降低速度 | 透明/细长物体 |
| 碰撞/超限 | QP 不可行；电流/位置异常 | 保持/后退；恢复 | 所有任务 |

### 5.5 不可逆动作

| 动作 | 任务 | 执行前 | 执行后 | 失败处理 |
|---|---|---|---|---|
| 倒水/注水 | T14, T32 | 目标杯对齐；瓶口/针头对准；抓稳 | 液位/流量验证 | 停止；保留 partial |
| 上锁 | T09 | 锁扣对齐；盖子闭合 | 锁上验证 | 不硬拧；重试/放弃 |
| 拉拉链 | T18, T19, T23, T31 | 拉链头抓住；布面平 | 拉链闭合验证 | 回滚；重拉 |
| 合盖 | T09, T17, T28, T29 | 盖子对齐；无杂物 | 闭合验证 | 重开/重试 |
| 拧紧/拧开 | T14 | 瓶口/盖子对齐 | 状态验证 | 重试/放弃 |

原则：**不确定就不做**；先重观测/换视角；宁可保留 partial score，也不要不可逆地做错。

### 5.6 安全-恢复的取舍

- **过度急停**：human 轴 20% 可能变 0；频繁启停丢失接触/抓取状态。
- **过度激进**：碰撞/超限/夹手；可能违规或损坏设备。
- **目标**：在硬安全约束下，最大化「步骤完成 + 可恢复」；不是最大化「静止」。
- **风险感知裕度**：人/不可逆动作/高速段大裕度；自由空间/低速/远离人小裕度。
- **指标**：成功率、步骤分、安全违规、恢复率、急停次数、p99 延迟；不要只看安全违规。

## 6. 训练与数据

### 6.1 步骤分割标签

- 官方 K 步（2–5）；重复步骤展开；
- 夹爪闭合事件 + 物体运动 + DTW；
- 人工抽查 5 条/task；边界误差 >2 帧的 episode 剔除/降权；
- 标签质量门：G1；不达标则退回 CHUNK-SERVO + 整任务条件。

### 6.2 步骤条件化微调

**数据**：

- 33,276 episodes；32 任务；94 步骤；5 条同义指令；
- 每帧标签：任务 ID、步骤 ID、步骤完成、抓取位姿（仅抓取帧）；
- 语言增强：官方 5 条 + 模板化改写（同义动词/目标别名）；
- 视觉增强：颜色/亮度/背景/干扰物（不改变几何标签）；位置/受器平移用于恢复数据。

**训练**：

```text
冻结 VLM
训练：DiT action head + robot-state projector + 小头
损失：L_action + λ1 L_step + λ2 L_progress + λ3 L_grasp + λ4 L_lang
优化：AdamW；学习率/批量按 WLA 微调配方；LoRA 可选
显存：24GB；先 1–2 卡消融
```

**基线**：

1. 官方 WLA + 整任务语言 + chunk 30；
2. 官方 WLA + 整任务语言 + chunk 5（CHUNK-SERVO）；
3. 官方 WLA + 步骤语言 + chunk 5；
4. 3 + 抓取先验（C2）；
5. 4 + 安全/恢复；
6. 5 + 抓取头/步骤头（C3，可选）。

### 6.3 抓取标签

- 从成功演示挖；过滤滑移/重试/空抓；
- 聚类去重；每类 top-K；
- 划分：按 episode/session/物体/背景分组；相邻帧不跨 split；
- 类别不平衡：多抓取任务（T15/T17/T27）权重高；单抓取任务权重低；
- 失败样本：空抓/滑移可以作为负样本（C3 抓取头），但不要污染演示先验。

### 6.4 扰动合成

**离线**（不需要第二模型）：

- 平移目标/受器：在演示中编辑物体位姿/ROI；或用数字孪生重渲染；
- 状态逆转：把演示倒放/编辑状态（拉链拉开、盖子打开、毛巾翻开）；用于训练步骤完成头/恢复检测；
- 目标拿走：删除/遮挡目标；用于失败检测；
- 人手/遮挡：在图像中叠加手/物体；用于检测鲁棒性；
- 传送带重置：编辑目标位置；用于 T24。

**数字孪生**：

## 7. 实验设计

### 7.1 离线指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 步骤分割准确率 | 边界误差 ≤2 帧的比例 | ≥90% |
| 抓取检索精度 | top-5 含几何有效抓取的比例 | ≥80% |
| 抓取位姿误差 | 相对演示/真值的平移/旋转误差 | ≤5mm/2°（刚体） |
| 步骤分类准确率 | 当前步骤 k 的分类 | ≥90% |
| 进度预测 AUC | `P(post_k)` 的判别 | ≥0.85 |
| 扰动检测延迟 | 从扰动到检测的帧数/时间 | ≤200ms |
| 安全违规率 | 仿真/回放中的碰撞/超限 | 比基线低 ≥50% |

### 7.2 仿真

**任务族**（3 个，覆盖主要接触模式）：

1. **Peg-in-hole**：PlugInEthernet/PlugCharger；测插入对准、最后 3 厘米、孔位移动。
2. **Hang/stack**：HangCup/StackBowls/PaperCupStacking；测挂/叠、目标移动、拿走。
3. **Zip/fold**：ZipUp/FoldTowel；测拉链/变形、状态逆转、闭合验证。

**扰动注入**：

- 平移目标/受器（抓取前/后）；
- 状态逆转（拉链拉开/毛巾翻开/盖子打开）；
- 目标拿走；
- 人手/遮挡；
- 传送带重置（T24 风格）；
- 延迟 0/50/100/150ms。

**指标**：成功率、步骤分、首次抓取成功率、恢复率、安全违规、超调、p99 延迟。

### 7.3 真机单任务通道

- 6 个任务：HangCup、PlugInEthernet、ZipUp、StackBowls、FoldTowel、ToolboxStorage；
- 每个 5 次 A/B：baseline vs H-GRASP；同一初始条件；
- 指标：成功率、步骤分、首次抓取成功率、恢复率、p99、安全违规；
- 通过：≥4/6 任务 +10pp 步骤分或成功率；FoldTowel 不回归 >5pp；安全违规不增加。

### 7.4 32×10 干跑

- N 端口隔离；`reset()` 干净；内存不涨；p99 ≤150ms；
- 32 任务 ×10 次；记录每步得分、抓取成功、恢复；
- 先不计分干跑；再正式提交。

### 7.5 实验门 G0–G9

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| **G0** | 官方步骤图能否解析成可执行图？ | 32/32 任务；94/94 步骤有 pre/post；人工抽查 10 任务无歧义 | 只做步骤文本条件；退回 CHUNK-SERVO |
| **G1** | 步骤分段是否可信？ | 每任务 5 条演示边界误差 ≤2 帧；重复步骤抓取次数正确 ≥90% | 用夹爪事件粗分段；减少步骤条件化 |
| **G2** | 抓取先验是否可检索？ | top-5 含几何有效抓取 ≥80%；相对位姿误差 ≤5mm/2°（刚体） | 改用任务级固定抓取；只用几何候选 |
| **G3** | 抓取是否真的涨点？ | 首次抓取成功率 +10pp；2 步任务步骤分 +10pp | 回退 VLA 直接抓；检查评分权重 |
| **G4** | 步骤条件化是否优于整任务条件？ | 3 个任务 A/B，步骤分 +5pp 或收敛更快 | 保留整任务条件 + 步骤 prompt 混合 |
| **G5** | 伺服是否仍然有效？ | 第 12 轮 G2/G3 复现：横向 ≤2mm、深度 ≤3mm、3/5 任务 +10pp | 保留 CHUNK-SERVO，不加步骤图 |
| **G6** | 安全滤波是否过度急停？ | 安全违规下降 ≥50%；成功率不降 >3pp | 放宽裕度/只保留硬约束 |
| **G7** | 扰动检测/恢复是否有效？ | 检测 ≤200ms；仿真恢复 ≥70%；human 轴 +15pp | 只做离线标注/不线上回滚 |
| **G8** | 长程复合是否改善？ | 4/5 步任务成功率 +10pp；步骤分 +10pp | 检查抓取复合/步骤推进逻辑 |
| **G9** | 32 任务干跑是否稳定？ | N 端口隔离、reset 干净、内存不涨、p99 ≤150ms | 回退基线；减头/减候选 |

### 7.6 消融

| 消融 | 比较 | 目的 |
|---|---|---|
| 步骤条件 | 整任务 vs 步骤 | 验证官方步骤图的价值 |
| 抓取先验 | 无 vs C2 vs C3 | 验证任务导向抓取的价值 |
| 伺服 | chunk 30 vs 5 | 复现第 12 轮 |
| 安全 | 无 vs QP/CBF | 验证安全层不降成功率 |
| 恢复 | 无 vs 回滚 | 验证 human 轴增益 |
| 抓取候选数 | M=4/8/16 | 精度/延迟折中 |
| 评分权重 | 默认 vs 任务特定 | 避免过拟合 |
| 语言 | 单条 vs 5 条同义 | 验证语言鲁棒性 |
| 机器人类型 | g1 vs g1_8520 | FoldTowel 特殊处理 |

### 7.7 统计分析

- 配对 A/B；同一初始条件；
- bootstrap 置信区间；不要只看均值；
- 320 trials 下 `p≈0.25` 的 SE≈2.42pp；+1–2pp 不足以声称结论；
- 步骤分是 tie-break，单独报告；
- 安全违规/恢复率/延迟单独报告；不要用成功率掩盖安全风险。

## 8. 竞赛策略

### 8.1 算术

- 总分 `S = (1/32) Σ_t p_t`；`p_t` 是任务 t 的 10 次平均成功率。
- 步骤分 tie-break：成功率相同看总平均步骤分；所以每一步都值钱。
- 3 步任务最后一步 40% ×14 = **5.6 个任务当量**；2 步任务第一步 50% ×11 = **5.5 个任务当量**；4/5 步任务抓取复合 = 7 个任务。
- human 轴 20%；恢复 +15pp → 全局 +3pp；+30pp → +6pp。
- 抓取 +10pp 在 2 步任务上 ≈ +1.7pp；长程复利另计；步骤条件化 +5pp 在 3 步任务上 ≈ +0.9pp；长程 +10pp ≈ +2.2pp。叠加是**假设**，必须 A/B 验证。

### 8.2 任务组合

| 档 | 任务特征 | 代表任务 | 主投 | 不投 |
|---|---|---|---|---|
| **A：2 步抓放** | 50/50；第一步抓取，第二步放置/挂/插/拉链 | T01, T02, T03, T05, T08, T14, T19, T23, T24, T30, T32 | 抓取先验 + 相对放置 + 恢复 | 复杂世界模型 |
| **B：3 步最后 40%** | 30/30/40；最后一步接触/闭合 | T04, T06, T07, T10, T11, T12, T13, T20, T21, T25, T26, T27, T29, T31 | 伺服 + 步骤条件化 + 不可逆门控 | 只堆语义数据 |
| **C：4/5 步长程** | 25×4 / 20×5；抓取复合、等权 | T09, T15, T16, T17, T18, T22, T28 | 抓取可靠性 + 步骤图 + 回滚 | 从头训长程策略 |

先验表，不是结论；单任务通道测完后用 `q_t×Δ/cost_t` 重排。

### 8.3 单任务通道协议

1. 6 个任务：HangCup、PlugInEthernet、ZipUp、StackBowls、FoldTowel、ToolboxStorage。
2. 每个 5 次 A/B：baseline vs H-GRASP；同一初始条件。
3. 记录：成功率、步骤分、首次抓取成功率、恢复率、p99、安全违规。
4. 通过：≥4/6 任务 +10pp；FoldTowel 不回归 >5pp；安全违规不增加。
5. 扫 `H_c ∈ {3,5,8}`、M、评分权重；选稳定折中。
6. 最后才跑 32×10。

### 8.4 提交节奏

- 若允许多次提交：先交安全基线（WLA + API 适配 + chunk 5/30 + 基本安全限幅），锁定 tie-break；再交 H-GRASP。
- 若只允许一次：先在单任务通道打磨，再交最终版。
- 不追预览榜单 29.7%；以官方步骤分/单任务通道为准。
- 不把 320 trials 浪费在「从零训 6B」「完整世界模型」「32 任务各训一个策略」上。

### 8.5 明确不投

- 从零训通用 VLA/World Model；
- 完整 sim-to-real 策略训练；
- 30Hz 广域网视觉伺服；
- 每任务学习策略；
- 通用 6D 物体位姿网络；
- 独立高层 planner；
- 力/触觉闭环（API 没有）；
- 第二个人体检测/安全学习模型。

## 9. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被抓取头/步骤头判为第二个模型 | 默认 C2（检索+几何+确定性滤波）；C3 只在确认后使用；提交材料写清「一个 checkpoint，多头共享 backbone」 |
| 步骤标注误差 | 条件化/监控错误 | 官方步骤 + 夹爪事件 + 人工抽查；边界误差 >2 帧剔除 |
| 抓取标签噪声 | 抓取先验偏差 | 只取成功演示闭合时刻；过滤滑移/重试；聚类去重；top-K 多样 |
| API 无深度 | 抓取定位不准 | 头双目恢复深度；腕部一次标定；透明/变形用 ROI/相对位姿 |
| 腕部无内参 | 2D 伺服/抓取偏差 | 棋盘格标定；D435 先验；头双目 PBVS 兜底 |
| 人检测误报/漏报 | 过度急停/碰撞 | 深度 blob + 本体感知；风险感知裕度；不依赖第二个人体模型 |
| 安全滤波过度保守 | 成功率下降 | 只保留硬约束；仿真扫裕度；成功率不降 >3pp 才上线 |
| 恢复回滚错误 | 反复重做/超时 | 最早被破坏的 post_j；最大重试；时间预算；优雅失败 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组；相邻帧不跨 split |
| 预览榜单误导 | 调参目标错误 | 不把 29.7% 当 SOTA；以官方步骤分/单任务通道为准 |
| 时间/算力 | 做不完 | 先 C2 抓取 + 步骤图 + 基本安全；C3/高级恢复后置 |
| T31/T32 无 human 备注 | 恢复策略不匹配 | 保守处理；不针对性调参；单独观察 |
| 评估集与训练集重叠 | 离线/真机虚高 | 按 episode/物体/背景分组；官方示例 episode 不训练 |
| 安全伦理 | 夹手/碰撞 | QP/CBF 硬约束；人在附近降速/暂停；不硬撞 |

**合规阶梯**：

- **C1**：抓取标签只用于离线分析/微调 action head；最低风险。
- **C2**：演示检索 + 几何评分 + 确定性伺服；默认主路径。
- **C3**：同一 checkpoint 加抓取头/步骤头；需确认「多头」解释；冲分路径。

**提交材料建议**：

- 明确写出：唯一学习模型是 WLA 微调后的 checkpoint；抓取检索/几何评分/安全滤波/恢复状态机是无学习权重的确定性组件；若用 C3，明确多头共享同一 backbone/checkpoint。
- 不把「第二个模型」藏在预处理里；不使用独立 CLIP/SAM/抓取网络在线推理。
- 安全层的目的不是「更保守」，而是「在硬约束下保留任务进度」；报告安全违规/恢复率/成功率三项。
