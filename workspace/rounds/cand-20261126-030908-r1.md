## 1. 两个灵感的第一性原理

### 灵感 1 ·「扩散策略」→ 它是「轨迹雕塑家」，不是「闭环控制器」

**直觉**：扩散策略像一位从噪声里雕出动作序列的雕塑家——它见过很多「好动作长什么样」，于是能把一团噪声逐渐削成一条平滑、像人演示的轨迹。但它只学过「数据流形」，没学过「物理可行域」；它也不知道自己雕出来的是不是正对着当前这个目标。它一次雕一整段（action chunk），雕完才执行，所以错误是「预谋」的，不是「反应」的。最危险的不是它画得丑，而是它画得又顺又自信，却穿过桌子、撞上干扰物，或者朝一个已经移动的目标伸手。

**严谨**：设动作 chunk 为 `a_{0:H} ∈ R^{H×d}`，扩散/流策略学习 `π_θ(a_{0:H} | o)` 的 score/velocity，采样即迭代去噪。它有三个结构性事实：

1. **只在流形上**：它建模 `p_data(a|o)`，不建模可行集 `C(o)`（工作空间、非穿透、关节限位、目标相对终态、抓取一致性）。因此样本可以高概率却不可行。
2. **chunk 承诺**：一次采样承诺 H 步；闭环反应被 chunk 长度限制；chunk 边界还可能出现模式切换（与 IP-03 的 jerk 问题同源）。
3. **多样本是免费资源**：推理时可抽 K 条，前 3 轮只用 1 条。K 条样本同时给出「候选」与「分歧」两种信号——这正是本轮两个新 IP 的原料。

**关键转译**：扩散策略的短板不是表达力，而是**缺少一个以场景为 ground 的批评器**。正确的补法不是再训一个更大的策略，而是在采样时把场景理解当作 **critic / constraint**：先做 best-of-K 场景批评重排（安全、免训练），必要时才做信任域内的路标级引导（更强，但会离开流形）。这把「模型能力」问题降级为「采样与选择」问题，和挑战赛「提交一个 policy 类」的接口天然契合。

**引理 L14（best-of-K 的收益与有效样本数）**：设 K 条样本的可行性指示 `X_k ∈ {0,1}` 可交换、`P(X=1)=p`、两两相关 `ρ`。独立时 `P(至少一条可行) = 1−(1−p)^K`；等相关时有效样本数 `K_eff = K/(1+(K−1)ρ)`，收益近似 `1−(1−p)^{K_eff}`。当 `ρ→1`，`K_eff→1`，重排收益归零。⇒ **best-of-K 只有在样本确实分散时才有用；必须先测多样性，再谈重排**（对应 IP-17）。∎

### 灵感 2 ·「场景理解」→ 从「描述世界」到「约束动作」

**直觉**：给图像配字幕的场景理解回答「有什么、在哪里」；给策略用的场景理解必须回答三个更窄的问题：**「我还能往哪动、什么必须避开、我还有什么不知道」**。前者是描述，后者是决策。把整张场景图塞给策略，既慢又容易学到虚假相关；真正有用的是任务相关的那一小块：目标、容器、支撑面、遮挡关系，以及它们的不确定度。场景理解的价值不在「看懂一切」，而在「只保留会影响动作的那部分」。

**严谨**：定义任务相关场景抽象 `S_τ = (E_τ, R_τ, U_τ)`：实体（位姿 + 协方差 + 供抓/可供性）、关系（目标–容器、支撑、包含、遮挡、干扰物邻近）、不确定度。它是 IP-13 场景图 `M=(T,D,F)` 在任务 τ 下的**商**（quotient），在工作台坐标系 `F` 中表达，而不是像素坐标。信息瓶颈形式：在约束 `I(S_τ; I) ≤ B` 下最大化 `I(S_τ; A*)`（`A*` 为最优动作/结果）。这给出三条设计后果：

1. **任务化**：只选与 τ 相关的实体/关系；全场景图是超集，不是接口。
2. **坐标化**：在工作台系表达 ⇒ 对相机配置（头+腕 vs 仅头）与末端（Dex1 vs Brainco）更不敏感，这是利用本轮新增跨本体数据的接口。
3. **带不确定度**：`U_τ` 不是附属品，而是 IP-16/17 的输入——它决定「这条样本能不能信」。

**引理 L16（任务相关抽象的充分性）**：若 `S_τ` 对最优动作是充分统计量（`I(A*; I | S_τ)=0`），则以 `S_τ` 为条件的策略达到与以原始观测为条件相同的 Bayes 风险；反之，加入与 `A*` 在给定 `S_τ` 下独立的冗余实体 `Z` 不降低 Bayes 风险，却会在有限样本条件下增大条件器的估计方差（方差增量随 `I(Z; I | S_τ)` 增长）。⇒ **场景理解应「任务化 + 最小化」，而不是「全场景 + 大模型」**。∎

### 1.3 两者交汇：Scene-as-Critic 的三层能力阶梯

- **Layer 0（安全，免训练）**：K 采样 + 场景批评重排 + 前 h 步执行（IP-16）。只做「选择」，不碰策略流形。
- **Layer 1（更强，仍免训练）**：若 K 条全部不可行/高度分歧，才在**路标/终点**做信任域软引导（P13 / L15）；不逐帧硬投影。
- **Layer 2（研究性，需训练）**：用 `S_τ` 做条件化/重训（IP-18），并测试跨相机/跨本体迁移。

三层有预注册门槛，**未过 Layer 0 不得跳 Layer 2**。

## 3. 设计原则（新增 P13–P15，接第 1–3 轮 P1–P12）

- **P13（约束只加在路标/终点，不逐帧投影）**：硬投影整段动作会离开策略流形；约束应施加在低维路标/终点与样本选择层，让策略自己生成可行插值（L15）。
- **P14（先选择后引导）**：能用 best-of-K 场景批评解决就不做 guidance；guidance 必须有信任域（KL/距离上限），且必须与无引导样本做 A/B。
- **P15（场景抽象任务化、最小化、坐标化）**：只保留任务相关实体/关系/不确定度，在工作台系表达；不做全场景描述，不用像素坐标作为跨本体接口（L16）。

## 5. 本轮最大风险（详述）

**批评器错配（critic misspecification）**：场景批评器如果奖励了「看起来可行但任务上错误」的 chunk（例如避开所有障碍却抓错物体、或选了一条平滑但到不了目标的轨迹），best-of-K 会把失败放大成「更自信的失败」。对冲：①批评器多特征（可行性 + 任务相关性 + 抓取一致性 + 平滑度）而非单一碰撞项；②保留共识分与基座策略的 A/B，批评器增益为负立即回退 K=1；③对「全不可行/无共识」只做保守介入（保持/重定位），不做大幅度换策略。

- **深化**：IP-16 的批评器特征与权重（用官方 URDF 做 FK/胶囊碰撞，E634）；IP-17 的结果签名与聚类（E636）；IP-18 的 TRSA schema 与仅头相机增广（E637）；IP-14 的仅头相机 SlipGuard 兜底（E630 扩展）。

## 7. 本轮结尾（一句话风险）

**当前方案的最大风险是：我们把「场景理解」压缩成批评器后，批评器的错配会被 best-of-K 放大成更自信的失败——即「选得更准，但选错时错得更彻底」。**

## 3. 新增 IP 详述

### IP-16 · SceneCritic Wrapper（P0，新）

- **动机**：扩散/流策略是「轨迹雕塑家」而非闭环控制器：它只在数据流形上采样，不显式建模可行集；一次采样承诺整段 chunk；但它天然给出 K 条候选。挑战赛接口允许对 action chunk 做后处理，因此「K 采样 + 场景批评 + 前 h 步执行」是零改服务端、零重训、可套任意提交模型的切入点。
- **与现有方案差异**：v3 的 IP-09/IP-13 是「执行时」的断言与伺服；IP-16 是「执行前」的样本选择。它不改变基座策略分布，只在 K 条合法样本中选，因此不会像 guidance 那样把动作推离流形（P13/P14）。
- **组件**：
  1. **K 采样**：同一观测、不同噪声抽 K 条 chunk（K=2–8，按延迟预算自适应）；支持扩散/流两类采样器。
  2. **场景批评器** `C(a; S_τ)`：`w1·可行性`（工作空间、FK 轨迹的胶囊/离散 SDF 非穿透、关节限位）+ `w2·任务相关性`（终态相对目标/容器的位姿、抓取对齐、干扰物距离）+ `w3·平滑度`（jerk + 与上一 chunk 的边界一致性）+ `w4·共识`（与其他样本的结果签名一致性）。
  3. **选择**：`argmax C`；同分用共识分裁决。
  4. **信任域引导（可选，Layer 1）**：若所有样本 `C < TAU_FAIL`，仅在**终点/路标**做软引导（低维、限步长、KL 上限），不逐帧硬投影；仍不可行则返回最不坏样本并触发 IP-02 介入。
  5. **滚动执行**：只执行前 `h < H` 步，保留闭环反应；送入 IP-03 做边界缝合。
- **技术可行性**：高。批评器全部是解析件：官方 `assets/urdf/g1_d_description/` 提供 G1 Dex1/Dex3 的 URDF 与 STL，可直接做 FK 与胶囊近似碰撞；工作空间/目标容差来自 IP-13 与 IP-06 标注。无需新数据、无需训练。
- **资源**：算力 = K 次基座前向 + 轻量 FK/几何检查；数据 = 0 新增；接口 = 无新增字段（全部策略内部）。
- **落地步骤**：①从 U19 定义批评器特征；②用官方 URDF 实现 FK + 胶囊/离散 SDF；③实现 K 采样 wrapper 与前 h 步滚动；④用 IP-06 代理评测标定权重（先规则、后轻量回归）；⑤A/B 基座与 K=1/2/4/8；⑥延迟实测（E635）。
- **风险**：批评器错配（最危险，见 §10）；模式坍缩使 `K_eff` 低；K× 延迟；场景状态误差传导。对冲：多特征批评、共识门、K 自适应、Level-2.0 退化。

### IP-17 · ConsensusGate（P1，新）

- **动机**：扩散策略的 K 样本给出免费的 epistemic 信号，但**动作空间方差会把「合法多解」误判为「不确定」**（例如两个都可行的抓取点）。正确做法是在**结果空间**看共识：把每条样本映射为低维结果签名（终态 EE 位姿、抓取点、子目标 id、目标相对变换），再聚类。
- **判据**（U21）：设聚类质量 `m_j` 与簇内离散度 `σ_j`，共识分 `κ = max_j m_j·(1−σ_j/σ_ref)`；若存在 ≥2 个「高 mass + 低离散」的簇 → **多解**（按场景批评选，不介入）；若没有紧簇（`max_j m_j < M_MIN` 或 `σ_max > S_MAX`）→ **歧义**（慢路径：加采样/重定位/保守保持）。
- **与现有方案差异**：v3 的复读检测看「行为是否重复」，IP-17 看「样本是否一致」；前者是时间维，后者是分布维。二者互补：复读 = 同一失败模式被反复采样；歧义 = 采样本身没有稳定模式。
- **可行性**：高。复用 IP-16 的样本，零额外前向；聚类与签名是轻量件。风险在签名选择与阈值校准。
- **资源**：近零；复用 IP-16/IP-13。
- **步骤**：①定义结果签名与距离；②实现聚类与 κ；③在 IP-06 上标注「多解/歧义/确定」三类；④校准阈值（E636）；⑤接入 IP-02（介入触发）、IP-04（上下文特征）、IP-15（保持 vs 重定位）。
- **风险**：签名丢掉关键差异；相关样本虚高置信（用 `K_eff` 校正）；阈值跨任务漂移。对冲：多签名投票、按任务校准、κ 仅作门控不作连续奖励。

### IP-18 · SceneLens / TRSA（P1，新）

- **动机**：本轮新增 Brainco（仅头相机、6-DoF 灵巧手）与 Fold_Clothes（形变）说明：像素条件的扩散策略是**本体/相机特定**的；场景理解若输出工作台坐标系下的任务相关抽象，则可作为跨本体接口。全场景图太重，且含大量与动作无关的实体；需要的是任务 τ 下的最小充分抽象。
- **定义**（U20）：`S_τ = (E_τ, R_τ, U_τ)`。`E_τ`：任务相关实体（目标、容器、支撑面、障碍/干扰物）及其位姿、协方差、供抓/可供性；`R_τ`：目标–容器、支撑、包含、遮挡、邻近等关系；`U_τ`：位姿/检测/关系的不确定度。全部在 IP-13 的工作台系 `F` 中表达。
- **与现有方案差异**：IP-13 的 U16 是「完整场景图」，IP-18 是它在任务下的**商**（只留动作相关部分）；IP-04 的 FiLM 是「统计量向量」，IP-18 是「结构化 token 集」。前者给策略调质，后者给批评器/条件器提供可解释的实体级证据。
- **可行性**：中。依赖 IP-13 的检测/位姿精度（E628）与任务规格覆盖；形变物体超出刚体档案范围，先记为 Q15 开放项。
- **资源**：现有 Dex1 数据 + IP-06 标注；小型选择器（先规则，后信息瓶颈）；无需新硬件。
- **步骤**：①schema 与任务规格模板；②规则版选择器（目标/容器/障碍/遮挡）；③用 IP-06 标注训练轻量 IB 选择器（辅助任务：预测下一路标/成功）；④跨相机增广：训练时随机丢弃腕部视角，模拟仅头配置；⑤在 Brainco 仅头数据上零样本评测（E637）；⑥先接 IP-16 批评器，不急于条件化策略。
- **风险**：抽象瓶颈丢掉关键细节（形变/透明/小物体）；位姿误差传导；任务规格工程量大；跨本体零样本失败。对冲：保留腕部/头部原始特征作残差；先做批评器不做重训；E637 门槛未过则收缩为诊断工具。

## 5. 符号与定义（新增 U19–U21；U1–U18 沿用第 1–3 轮）

- **定义 U19（场景条件可行集）**：`C(o) = { a_{0:H} : traj(a) ⊆ W, clearance(traj(a)) ≥ 0, joint_limits(a), terminal_rel(a) ∈ Tol(g_i), grasp_consistent(a, T) }`；`W` 为工作空间，`clearance` 由 FK + 胶囊/离散 SDF 近似，`Tol(g_i)` 为路标 `g_i` 的目标容差域，`T` 为目标档案。软版本 `C_ε` 用惩罚 `Φ_C` 代替硬约束，供信任域引导使用。
- **定义 U20（任务相关场景抽象）**：`S_τ = (E_τ, R_τ, U_τ)`；`E_τ` 为任务相关实体（含位姿 `x̂`、协方差 `Σ`、供抓/可供性），`R_τ` 为关系集（目标–容器、支撑、包含、遮挡、邻近），`U_τ` 为不确定度；`S_τ = Q_τ(M)` 是 U16 场景图 `M` 在任务 `τ` 下的商，在工作台系 `F` 表达。信息瓶颈：`max I(S_τ; A*) s.t. I(S_τ; I) ≤ B`。
- **定义 U21（共识/歧义）**：对 K 条样本的结果签名 `φ(a^(k))`（终态 EE 位姿、抓取点、子目标 id）聚类得 `{C_j, m_j, σ_j}`；`κ = max_j m_j(1−σ_j/σ_ref)`。**多解**：≥2 个簇满足 `m_j ≥ M_MIN` 且 `σ_j ≤ S_TIGHT`；**歧义**：`max_j m_j < M_MIN` 或 `σ_max > S_MAX`；**确定**：单簇且 `σ ≤ S_TIGHT`。三类对应不同介入策略。

## 6. 关键算法骨架（新增片段；主体沿第 1–3 轮 `UniBotSAGEPolicy`）

```python
# ===== IP-16: SceneCritic Wrapper（K 采样 + 场景批评 + 前 h 步滚动）=====
class SceneCriticWrapper:
    def __init__(self, base_policy, state, critic, K=4, H_exec=4):
        self.base, self.state, self.critic = base_policy, state, critic
        self.K, self.H_exec, self.prev = K, H_exec, None

    def get_action(self, obs):
        self.state.update(obs)                       # IP-13 低频 + 事件触发
        S = scene_lens(self.state, obs.task)         # U20: 任务相关抽象
        C = feasible_set(self.state, S)              # U19: 可行集
        chunks = self.base.sample(obs, self.K)       # 扩散/流 K 条候选
        feats  = [self.critic.features(a, S, C, self.prev) for a in chunks]
        scores = self.critic.score(feats)
        kappa, multimodal_tight = consensus(feats)   # U21
        if scores.max() >= TAU_OK:
            a = chunks[scores.argmax()]
        elif multimodal_tight:
            a = chunks[scores.argmax()]              # 多解：按场景选，不介入
        elif scores.max() >= TAU_FAIL:
            a = trust_region_guide(chunks, C) or chunks[scores.argmax()]
            self.intervene("AMBIGUOUS")
        else:
            a = chunks[scores.argmax()]
            self.intervene("ALL_INFEASIBLE")         # 交 IP-02
        self.prev = a
        return a[:self.H_exec]                       # 滚动执行，保留反应性
```

```python
# ===== 场景批评器特征（解析件，无学习）=====
def critic_features(a, S, C, prev):
    traj = fk(a)                                     # 官方 URDF: G1 Dex1/Dex3
    clearance = min_sdf(traj, S.obstacles)           # 胶囊/离散 SDF 近似
    ws        = inside_workspace(traj, C.W)
    term      = task_relevance(traj[-1], S.target, S.receptacle)
    grasp     = grasp_consistency(traj, S.target.affordance)
    smooth    = jerk(a) + boundary_jerk(a, prev)
    return dict(clearance=clearance, ws=ws, term=term,
                grasp=grasp, smooth=smooth)
```

```python
# ===== IP-17: 结果空间共识（区分多解 vs 歧义）=====
def consensus(feats):
    sig      = [outcome_signature(f) for f in feats] # 终态位姿/抓取点/子目标 id
    clusters = cluster(sig, eps=EPS)
    masses   = [len(c) / len(sig) for c in clusters]
    disp     = [within_dispersion(c) for c in clusters]
    kappa    = max(m * (1 - d / SIGMA_REF) for m, d in zip(masses, disp))
    tight    = [i for i, (m, d) in enumerate(zip(masses, disp))
                if m >= M_MIN and d <= SIGMA_TIGHT]
    return kappa, len(tight) >= 2                    # 多解标志
```

```python
# ===== Layer 1: 只对终点/路标做信任域软引导（不逐帧硬投影）=====
def trust_region_guide(chunks, C):
    for a in chunks:
        for _ in range(DENOISE_STEPS):
            g = grad_penalty(terminal(a), C)         # 低维 d，非 H·d
            a = a - ETA * clip(g, -TRUST_EPS, TRUST_EPS)
    return best_by_critic(chunks)                    # 仍交给 IP-16 选
```

## 7. 推导（新增引理 L14–L16；L1–L13 沿用第 1–3 轮）

**引理 L14（best-of-K 的收益与有效样本数）** 设 K 条样本的可行性指示 `X_k ∈ {0,1}` 可交换、`P(X=1)=p`、两两相关 `ρ`。独立时 `P(至少一条可行)=1−(1−p)^K`；等相关时 `K_eff = K/(1+(K−1)ρ)`，收益近似 `1−(1−p)^{K_eff}`。`ρ→1 ⇒ K_eff→1`，重排收益归零。⇒ best-of-K 的收益由**样本多样性**而非 K 本身决定；必须先测 `K_eff`/共识，再决定是否值得多采样。∎

**引理 L15（约束位置与流形失真）** 设基座策略分布 π 支撑在演示动作流形 M 上。若硬投影 `P_C` 的像含有 M 之外的点（非凸碰撞约束下一般成立），则 `P_C#π` 在 M 外有质量而 π 没有，`D_KL(P_C#π || π) = ∞`：逐帧硬投影必然把动作推离策略流形。把约束改为只作用于 d 维路标/终点、并以信任域 `||Δ|| ≤ ε` 限制修正量，则修正维度从 `H·d` 降到 `d`；局部高斯近似下 KL 上界由 `ε²/(2σ²)` 控制。⇒ **约束只加在路标/终点，且必须带信任域**（P13/P14）。∎

**引理 L16（任务相关抽象的充分性）** 若 `S_τ` 对最优动作是充分统计量（`I(A*; I | S_τ)=0`），则以 `S_τ` 为条件的策略达到与以原始观测为条件相同的 Bayes 风险。反之，加入与 `A*` 在给定 `S_τ` 下独立的冗余实体 `Z`（`I(Z; A* | S_τ)=0`）不降低 Bayes 风险，却在有限样本下增大条件器估计方差，方差增量随 `I(Z; I | S_τ)` 增长。⇒ 场景理解应「任务化 + 最小化」，全场景图不是接口（P15）。∎

## 12. 本轮最值得押注的创新点（一句话）

**押注 IP-16（SceneCritic Wrapper）：它把「扩散策略只会采样、不会判断」这一结构性短板，转成「K 采样 + 场景批评 + 前 h 步执行」的接口内后处理——零重训、零新数据、可套任意提交模型，直接吃 IP-13 的状态与官方 URDF，向下把失败拦在执行前、向上给 IP-17/18 供信号；在新数据跨相机/跨本体、底座趋同的窗口期，它是最贴近赛制、又最难被「换个更大的策略」一夜抹平的工程护城河。**

**一句话风险**：批评器的错配会被 best-of-K 放大成更自信的失败——选得更准，但选错时错得更彻底。
