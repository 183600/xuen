# 第 1 轮（新循环）· FORCE-SHADOW：无传感器力控 + 桌面坐标系 + 接触感知 VLA，把「最后 3 厘米」变成可测的力影

> 检索/复核日期：**2026-10-29（UTC）**。赛事身份已核实：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新灵感循环的第 1 轮，三个词是「力控」「桌面操作」「视觉-语言-动作模型」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是在它们之上换一个更硬的支点：**不再只问“孔在哪里”，而是问“我有没有顶住、顶偏、顶死”**。一句话：**用位置指令与实测位姿的残差当“力影”，在桌面坐标系里对 5 步 chunk 做方向性柔顺与接触前减速；VLA 仍是唯一学习模型，力控是确定性控制器。**

## 0. 先给结论：榜首不到 30%，缺的不是“更大的 VLA”，而是“接触段的力觉闭环”

截至 2026-10-29，官方榜单 JSON 仍返回 8 个预览模型：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。但同一天，`leaderboard.html` 与 `runs.html` 的页面正文显示 **“Coming Soon / 即将发布”**，只有 JSON 还保留旧数据。这更像是“页面在改版/榜单在重置”，而不是“榜单实时更新”。因此本轮仍把 29.7% 当作**难度信号/预览上限**，不当作 SOTA，也不从它的任务排名里挖创新点。

本轮真正改变判断的三条新事实：

1. **官方 WLA-1.0 很可能已经“见过”这 32 个任务。** HuggingFace 的 `UnifoLM-WLA-1.0` collection 明确把 `UniBot-V1 Challenge Dataset` collection 列为数据 collection；WLA 微调文档也直接用 `G1_Dex1_HangCup` 等同名数据。这意味着：**从零训一个 6B/14B 不是边际收益最高的方向；真正的差距在“同一批任务上的执行、接触与泛化”。**
2. **挑战赛 API 没有力/力矩/电流，只有位置。** 观测是四路 RGB + 双臂关节 `[7]` + EE 位姿 `[6]` + 夹爪 `[1]` + 下身体 `[15]` + 语言；动作是 `joint` 或 `ee` 的位置目标；没有 depth、camera_info、force/torque、tactile、motor current。Dex1 本体有电机力矩反馈、夹持力可调 5–120 N，但这些**没有暴露给选手**。所以“直接力控”不可行，必须做**无传感器力估计**。
3. **G1 的低层位置控制器本身就是一台“力传感器”。** Unitree SDK 的 G1 手臂低层控制是 `τ = kp(q_des − q) + kd(dq_des − dq) + τ_ff`，手臂关节常用 `kp≈40–60`、`kd≈1–1.5`。在位置目标与实测位姿之间，稳态误差乘以刚度就是机器人正在施加的力。**我们不需要额外的力传感器；我们需要把“跟踪误差”翻译成“接触力影”。**

所以本轮的押注是 **FORCE-SHADOW**：

> 用官方 WLA 做慢速语义规划；用 5 步 chunk 执行；在每个 chunk 边界，用上一段 chunk 的位置目标与实测位姿之差估计 6D 力影；用桌面平面把力影分解为法向/切向；用法向柔顺、切向保刚、接触前减速和夹爪滞止检测，把“最后 3 厘米”从位置开环变成力觉闭环。

一句话：**视觉告诉机器人“孔在哪”，力影告诉机器人“是不是顶住了”；两者叠加，才是接触密集桌面任务的完整闭环。**

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **力控** | FORCE-SHADOW：位置误差→关节力矩→EE 6D 力影；软件柔顺 `x_cmd = x_nom − C(F_hat − F_d)`；夹爪滞止→抓取力日程 | 不做直接力矩控制（API 没有）；不假设有力传感器；不加载第二个学习策略 |
| **桌面操作** | TABLE-FRAME：用头部双目估计桌面平面，把动作/力影变换到桌面坐标系；法向柔顺、切向保刚；桌面高度/倾斜/背景变化被几何归一化 | 不把桌面当成“又一个语义类别”；不做 6D 物体位姿网络；不对变形任务硬做刚体柔顺 |
| **VLA** | 官方 WLA 6B 做 30 步慢规划；5 步执行；接触模式头（第二阶段）作为同一 checkpoint 的辅助头；接触段过采样与 chunk 边界采样 | 不从零训 VLA/World Model；不让世界模型直接接管 30Hz 控制；不做 32 个任务各一个策略 |

## 1. 本轮先核实了什么（只列会改变方案的）

### 1.1 赛事与规则：单模型、32 任务、10 次/任务、5 类泛化各 2 次、单任务不计分通道

参赛手册（2026-10-29 通过 `r.jina.ai` 重新抓取）与第 12 轮一致：

- 所有任务须基于**同一模型**完成，不得混合多个模型；模型类型不限（World Model、VLA 均可）。
- 32 个任务，每个任务 10 次独立运行；5 类泛化各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
- 单次真机执行上限 **180 s**；排名先看 32 任务总平均成功率，再相同看总平均步骤分，再相同看更早提交。
- 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态必须隔离。
- 另有**不计分的单任务测试通道**，可用于单任务成功率/步骤分验证。
- 挑战赛页面（2026-10-29）写明：**“申请测试：预约评测时段”**。这意味着评测不是无限次随便跑，正式 slot 是稀缺资源；单任务通道和离线 A/B 的重要性进一步上升。

**对方案的约束**：FORCE-SHADOW 必须每端口独立、CPU 轻量、不抢 GPU；力影/柔顺是确定性控制器；VLA 是唯一学习策略；不能为每个任务训一个残差策略。

### 1.2 接口：四路 RGB、无深度/力/触觉，`action_chunk_size` 决定反馈周期

提交模板 README（2026-10-29 复核）给出：

- 观测：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB 480×640；双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str`。
- 动作：`joint` 或 `ee` 互斥；`ee` 模式是**绝对目标位姿**（xyz+rpy，base 系）；共享 `left_gripper [1]`、`right_gripper [1]`、`pivot [7]`。
- `action_chunk_size` 固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action`；**chunk 内没有新观测，也没有打断机制**。
- `obs_delta_indices` 决定传哪些键、堆叠几帧；`image_resize` 可缩放；`meta.token` 每次 `get_action` 都要带。
- **没有 depth、camera_info、force/torque、tactile、motor current。**
- 评测端逐调用记录延迟、波动和动作统计规律，作为结果可信度的一部分。

**关键推论**：`action_chunk_size=30`、30Hz 时一次 `get_action` 后有 **1 秒开环执行**；即使 `chunk=5`，也只有 **167ms** 的执行块和 **6Hz** 的外环。力控不能靠“高频力矩环”，只能靠**低层 PD 的内环柔顺 + 策略层 6Hz 的力影外环**。这反而适合我们：低层 PD 在 1kHz 内环里已经把“顶住”变成了位置误差，我们只需要在外环读它。

### 1.3 数据：33,276 条 / 169.28 h / 32 任务；没有力标签；腕部无内参

32 个 HF 数据集合计（2026-10-29 复核）：

|---|---:|
| episodes | **33,276** |
| frames | **18,282,246** |
| 时长 | **169.28 h**（30 fps） |
| 任务数 | 32 |

关键细节（与第 12 轮一致，但本轮重点不同）：

- 四路视频：`head_stereo_left/right`、`wrist_left/right`，均 480×640；头部双目已校正，基线 **58.2526 mm**，`fx≈282 px`；腕部相机**没有内参矩阵**。
- `state_d435` 是头相机在 base 系的 6D 位姿；`lower_body[-3:]` 与 `waist_state_joint` 一致；线上 API 给 `lower_body`，头相机外参可在线恢复。
- **数据里没有 force/torque/current 列。** 只有位置、EE 位姿、夹爪位置、动作目标。这意味着力标签只能**自监督**地从“动作-状态残差”和“夹爪滞止”里挖。

### 1.4 官方 WLA：6B、30 步、24GB 微调；它很可能已经覆盖挑战赛 32 任务

官方 UnifoLM-WLA-1.0（2026-09-28 开源）事实：

- **6B** 参数；约 **2,500 h** 真机数据；64 个任务（桌面 + 全身）；二指夹爪 + 五指灵巧手。
- 默认 `chunk_size=30`、`target_fps=30`，覆盖约 `[0, 29/30]` 秒；4 步扩散去噪。
- 统一动作 **54 维**、状态 **60 维**；EE 动作是**相对当前 EE** 的 xyz+rotvec；微调时冻结 VLM（`qwen_vl_interface`），只训 DiT action head + robot-state projector；默认单张 **24GB** GPU。
- 模型服务器输入 `cam_left_high` + 左右腕部三路图；输出 30 步 chunk；挑战赛 API 的 `ee` 是**绝对**目标位姿，WLA 是**相对**动作，adapter 必须先 compose 到当前绝对位姿，再切片。
- **HuggingFace `UnifoLM-WLA-1.0` collection 明确包含 `UniBot-V1 Challenge Dataset` collection**；WLA 微调文档也直接使用 `G1_Dex1_HangCup` 等同名数据。这不是“同名巧合”的强证据，但也不是官方逐任务训练清单；必须在单任务通道验证 WLA 对 32 任务的实际覆盖。

**战略结论**：不要从零训 6B/14B；不要把“更大的世界模型”当第一优先级。用 WLA Base 做适配/轻微微调，把省下的算力投到**接触层**和**单任务评测**。如果 WLA 已经见过 32 任务，那么“知识”不是瓶颈，“最后 3 厘米的力觉执行”才是。

### 1.5 硬件：G1 的 PD 控制器就是“力传感器”；Dex1 有力矩反馈但 API 不给

- G1 低层手臂控制：`τ = kp(q_des − q) + kd(dq_des − dq) + τ_ff`；官方示例手臂 `kp≈40–60`、`kd≈1–1.5`；不同关节/配置略有差异。
- Dex1-1：夹持力可调 **5–120 N**；电机状态反馈含 **角度、角速度、力矩、温度**；控制指令支持 **角度、角速度、力矩、刚度、阻尼**。但挑战赛 API 只给 `left_gripper [1]` / `right_gripper [1]` 位置，动作也只发位置目标。**硬件有能力，接口没开放。**
- 这给出两个可用信号：
  1. **臂的力影**：`τ_hat = kp ⊙ (q_cmd − q_obs) + kd ⊙ (dq_cmd − dq_obs)`，再用 `J^{-T}` 映射到 EE 6D wrench；或者直接在 `ee` 模式用 `F_hat = K_x (x_cmd − x_obs)`。
  2. **夹爪的滞止**：命令继续闭合而实测夹爪位置停在某宽度，说明夹住了物体；`g_stall = a_g − s_g` 是抓取/滑移/物体宽度的代理。

### 1.6 榜单：29.7% 是“预览上限”，不是可复现实验；页面正在改版

第 12 轮已经对 `leaderboard_data.json` 做过取证：`generated_from=gen_leaderboard.py`；8 模型 ×32 任务的 `step ~ success` 回归 `R²>0.999999`；详情页视频全是占位；10 次 trial 却出现 27.29%、27.85% 等非 10% 整数倍；跨模型任务成功率平均相关只有 0.098。本轮复核 JSON 数值未变，且 `leaderboard.html`/`runs.html` 显示 **Coming Soon**。

**结论**：把 29.7% 当“赛事方给的难度信号/预览上限”可以；当 SOTA、当任务难度表、当失败分布都不可以。本轮不从榜单任务排名挖创新点，只从**官方数据、接口、硬件和公开模型家族的技术路线**挖。

### 1.7 力觉 VLA 很热，但都绕不开“有 F/T 或高频力矩接口”这个前提

2026 年的力觉 VLA 已经很多，但和本赛题的关键差异如下：

| 工作 | 做法 | 与本赛题的关键差异 |
|---|---|---|
| **ForceVLA / ForceVLA2**（NeurIPS 2025 / CVPR 2026） | 力提示 + 力感知 MoE；混合力位控制 | 需要 6 轴 F/T 或力信号；本赛题 API 没有 |
| **TAO-Force**（arXiv 2609.18497） | 力条件 FiLM + 接触门控快慢控制 | 需要力反馈；快慢控制依赖低层力矩/柔顺接口 |
| **FAVLA**（arXiv 2602.23648） | 快慢 VLA；高频力特征注入 | 需要高频力序列；本赛题只有 6Hz 外环 |
| **CR-VLA-Force**（arXiv 2609.05832） | 控制感知柔顺 VLA；自适应柔顺控制器 | 需要 F/T；依赖 action chunk 内的快速力跟踪 |
| **FD-VLA**（arXiv 2602.02142） | 无物理力传感器的“力蒸馏” | 训练仍需要真实力信号做对齐；本赛题数据没有力 |
| **CompVLA**（arXiv 2609.23614） | VLA 联合预测运动 + 刚度矩阵，几何阻抗控制 | 最接近“预测柔顺”；但假设有可执行阻抗的低层接口，且未解决无力的监督 |
| **PaCo-VLA**（arXiv 2606.00515） | 把 VLA 输出当柔顺提议，用 passivity shield 管住 | 需要力/力矩监控与高频 admittance 端口；本赛题只有位置 API |
| **FAWAM**（arXiv 2606.08555） | 力感知世界动作模型 + 力残差校正 | 需要实时力反馈；本赛题没有 |
| **Minimalist Compliance Control**（arXiv 2603.00913） | 用电机电流/PWM 做无传感器柔顺 | 需要电流/PWM；本赛题 API 不给 |

**研究空白**：现有工作要么“有力量测量”，要么“有力矩/电流接口”，要么“有高频低层控制器”。本赛题是**三无**：无 F/T、无电流、无高频力矩接口，只有 30Hz 位置目标和位置反馈。**谁能把位置误差变成可靠的力影，谁就能在这个赛题上做出别人复制不了的接触层。**

### 1.8 本轮新增的离线证据：动作-状态残差在接触段放大 3–4 倍

我从官方数据里抽了两个单 shard 做验证（2026-10-29）：

- `G1_Dex1_HangCup/data/chunk-000/file-000.parquet`：**719 episodes / 130,565 frames**。
- `G1_Dex1_PlugInEthernet/data/chunk-000/file-000.parquet`：**211 episodes / 129,272 frames**。

方法：取双臂 14 维关节 + 2 维夹爪，用当前状态、当前动作、前 1/2 帧动作做 ridge 回归，预测下一帧状态；残差 `r_t=||s_{t+1}−f(s_t,a_t,a_{t−1})||`；按 episode 归一化时间分 10 桶；用前 30% 的中位残差做基线，算 `ratio`。

结果（节选）：

| 任务 | 相位（归一化时间） | 残差 ratio | 夹爪指令-实测误差 |
|---|---:|---:|---:|
| HangCup | 0.3–0.4 | **3.17** | ≈0 |
| HangCup | 0.4–0.5 | **3.02** | ≈0 |
| HangCup | 0.8–0.9 | **3.89** | ≈0 |
| PlugInEthernet | 0.1–0.2 | 1.78 | +0.01 |
| PlugInEthernet | 0.2–0.3 | 1.91 | −0.06 |
| PlugInEthernet | 0.3–0.4 | 1.62 | **−0.24** |
| PlugInEthernet | 0.6–0.7 | 1.28 | **−0.24** |
| PlugInEthernet | 0.7–0.8 | 0.75 | **−0.34** |
| PlugInEthernet | 0.9–1.0 | **2.00** | ≈0 |

两个额外观察：

- HangCup 的残差最大值时间中位数在 **0.39**，75 分位 **0.45**，90 分位 **0.79**；PlugInEthernet 的中位数 **0.51**，75 分位 **0.90**，90 分位 **0.94**。这说明残差尖峰集中在“抓/挂/插”的接触相位，而不是均匀分布。
- 残差与夹爪误差的相关系数只有 **0.02（HangCup）/ −0.02（PlugInEthernet）**，两者**互补**：臂残差抓“顶/推/插”，夹爪滞止抓“夹住/滑移”。

**必须说明的局限**：这是单 shard、无真值接触标签、ridge 自由空间模型带 2–3 帧动作滞后的初步分析；残差里混有未建模动力学、摩擦、快速运动。它证明“信号存在”，不证明“检测器已经可用”。下一步必须用腕部视频/夹爪滞止做真值标签，测 AUROC/误报，再决定是否上线。

## 2. 诊断：最后 3 厘米缺的是“力”，不是“看得更清”

把一次接触失败拆开：

```text
视觉：孔在图像里偏左 3px → 视觉伺服可以修
力觉：插头已经顶住孔沿，但策略还在往前推 → 视觉看不出来，越推越歪
夹爪：物体在指间滑了 2mm，但夹爪位置只变了 0.1 → 没有力反馈，抓取力不会加
人为干扰：人把杯子挪了 5cm，机器人还在按旧计划走 → 视觉可能看到，但本体没有“被推/被挡”的即时信号
```

三类失败，三种信号：

| 失败模式 | 视觉伺服 | 力影 | 夹爪滞止 | 组合 |
|---|---|---|---|---|
| 横向偏 2–5mm | 强 | 弱 | 无 | 视觉主导 |
| 插入顶死/过冲 | 弱（被夹爪/物体遮挡） | **强** | 弱 | 力影主导 |
| 抓空/滑移 | 中 | 弱 | **强** | 夹爪主导 |
| 人为移动物体 | 中（需重识别） | 弱（未接触） | 无 | 视觉+重定位 |
| 人推机器人 | 弱 | **强（立即）** | 无 | 力影主导 |
| 透明/反光物体 | 弱 | **强（接触即知）** | 中 | 力影兜底 |

所以本轮不是“再做一个视觉伺服”，而是**在 CHUNK-SERVO 的视觉环上再加一个力影环**：

```text
VLA 30 步慢规划
   ↓
5 步 chunk 执行
   ↓
每个 chunk 边界：
  视觉伺服（横向对孔） + 力影（法向柔顺/顶死回退） + 夹爪滞止（抓取力）
   ↓
桌面坐标系：法向软、切向硬；接触前减速；接触后限力
```

### 3.2 I1 · FORCE-SHADOW（P0，主投）

**动机**：API 没有力，但接触密集任务（插入、挂、叠、拉链、拧、锁）占 32 任务的大头；最后 3 厘米的失败不是“看不见”，而是“顶住了还在推”。

**与现有方案的差异**：
- ForceVLA/ForceVLA2/TAO-Force/FAVLA/CR-VLA-Force 都需要 F/T 或高频力序列；本方案只需要位置目标 + 位置反馈。
- FD-VLA 做“无传感器力蒸馏”，但训练仍需真实力；本方案用**动作-状态残差**做自监督伪力，不需要任何力标签。
- Minimalist Compliance Control 用电机电流/PWM；本赛题 API 不给电流，本方案用**位置误差×PD 刚度**替代。

**技术可行性**：
- 低层 PD 的力矩公式公开；G1 手臂 `kp/kd` 有官方示例；EE 力影 `F_hat = K_x (x_cmd − x_obs)` 只需要目标位姿和实测位姿。
- 观测里已有 EE 位姿；`obs_delta_indices` 可以带 5 帧历史；`action_chunk_size=5` 时每个边界都能算一次。
- 离线已验证残差在接触相位放大 3–4 倍；在线只需一个低通+阈值+方向分解。

**所需资源**：官方 33k 演示（离线拟合自由空间基线）；G1 URDF/Jacobian（或 EE 刚度标定）；CPU；不需要额外硬件。

**落地步骤**：
1. 用官方数据拟合自由空间残差基线（ridge/线性模型即可），按任务/机器人分片。
2. 在 `ee` 模式实现 `F_hat = K_x (x_cmd − x_obs)`；用重力和惯性基线去掉常驻分量。
3. 计算接触分数 `c=||F_hat||/σ`、方向 `n=F_hat/||F_hat||`；低通+滞回。
4. 用夹爪滞止和腕部视频做真值，测 AUROC/误报；先离线，再单任务通道。
5. 把 `c,n` 接到 I2 的柔顺层；先只做“顶死回退”，再做“法向限力”。

**风险**：位置误差混有控制滞后/摩擦；绝对力标定不准；快速运动误报。缓解：只用**相对变化**和**方向**，不追求绝对牛顿；用自由空间基线；融合夹爪/视觉；接触段降增益。

### 3.3 I2 · COMPLIANT-CHUNK（P0，与 I1 配对）

**动机**：chunk size 固定、chunk 内无新观测；接触发生在 chunk 内部时，策略只能等下一个 chunk。既然不能改 chunk size，就改 **chunk 内的运动包络**。

**与现有方案的差异**：
- Adaptive Action Chunking 用动作熵改 chunk 长度；本赛题 metadata 固定，不能逐任务改，所以本方案做**固定 chunk 的接触前整形**。
- CompVLA 预测刚度矩阵并依赖几何阻抗控制器；本方案用**位置 API 上的软件柔顺**：`x_cmd = x_nom − C(F_hat − F_d)`，等效刚度 `K_eff=(I+K_r C)^{-1}K_r`。
- PaCo-VLA 用 passivity shield 管柔顺提议；本方案也加一个简化能量罐，但不需要力传感器。

**技术可行性**：
- 位置 API 下，软件柔顺是“改设定点”，低层 PD 仍是 1kHz 内环；外环 6Hz，稳定性可用小 `C` + 低通 + 能量罐保证。
- 桌面坐标系让 `C` 只需两个数：法向 `c_n`、切向 `c_t`；不需要 6×6 全矩阵学习。
- chunk 整形只是在返回前对 5 步动作做缩放，计算量可忽略。

**所需资源**：仿真（MuJoCo/IsaacLab）调 `C/F_d/阈值`；单任务通道 A/B；CPU。

**落地步骤**：
1. 在仿真里实现位置控制 + 软件柔顺，扫 `c_n/c_t`、延迟、摩擦，找稳定域。
2. 定义接触模式与 `C` 表：FREE/APPROACH/GRASP/INSERT/PRESS/RETRACT。
3. 用 `p_contact` 做 chunk 包络：远距离全速；预接触 `[1,0.8,0.5,0.3,0.1]`；接触 `[1,0.5,0.2,0,0]`；顶死 `[1,0,0,0,0]` 并回退。
4. 单任务通道 A/B：servo only vs force-shadow+compliance；至少 3/5 任务 +10pp。
5. 通过后才进 32 任务正式评测。

**风险**：6Hz 外环 + 延迟可能振荡；位置式柔顺的力跟踪精度有限；过度柔顺会导致抓取/插入失败。缓解：仿真扫稳定域；法向软、切向硬；限幅；能量罐；失败回退 VLA 开环。

### 3.4 I3 · TABLE-FRAME（P1，便宜且高杠杆）

**动机**：32 个任务几乎都在桌面上；桌面是已知支撑面，但通用 VLA 把绝对 base 系位姿当动作，浪费容量在“桌子多高/多斜/背景是什么”上。位置/背景泛化轴正好考这个。

**与现有方案的差异**：
- 不是“再做一个桌子检测器”，而是把动作/力影/柔顺都变换到**桌面坐标系**：`z_t` 是法向，`x_t/y_t` 是切向；插入/按压/放置共用一套几何。
- VLA 不用重训：WLA 仍在 base 系输出；控制器在桌面系做柔顺，再变回 base 系。后续可选微调 table-frame 动作。

**技术可行性**：头部双目已校正；RANSAC 平面 + 工作区掩码即可；桌面高度/倾斜可每 episode 估一次；估计失败回退固定标定。成本极低。

**所需资源**：双目深度（SGBM/RAFT-Stereo 均可）；CPU；一次标定。

**落地步骤**：
1. 用头部双目生成深度，工作区 RANSAC 平面；法向朝上；yaw 用 base x 投影或桌沿。
2. 把 `x_nom`、`F_hat` 变换到桌面系；柔顺矩阵在桌面系对角。
3. 估计置信度低时回退 base 系；透明/反光桌面用固定标定。
4. 在位置/背景泛化上做 A/B：table-frame on/off。

**风险**：桌面被遮挡/反光/堆满物体；平面估计错会把插入方向带偏。缓解：多帧融合；只取桌面边缘/低处 ROI；与固定标定做一致性检查；置信度低回退。

### 3.5 I4 · CONTACT-CENTRIC DATA ENGINE（P1，数据侧）

**动机**：33k 演示里大部分帧是自由空间；接触段只占少数，但决定成败。标准 BC 对接触段欠采样；训练帧与 5 步执行也不一致。

**与现有方案的差异**：
- 不生成新数据，而是**重采样 + 伪标签 + chunk 边界对齐**：用 I1 的残差和 I6 的夹爪滞止给接触段打分；过采样接触前/接触中；按 5 步边界采样；加动作噪声模拟执行漂移。
- 与 FACT-VLA 的相位化 BC 兼容：接触段权重更高，相位标签来自残差/夹爪，不靠人工。

**技术可行性**：纯离线；ridge/轻量 MLP 即可；不改变 WLA 结构；可与 I5 辅助头共用标签。

**所需资源**：CPU/GPU；169h 数据；无需新采集。

**落地步骤**：
1. 全量计算残差/夹爪滞止/腕部接触（可选），生成每帧接触分数。
2. 按 `w=1+3*contact` 过采样；接触前 5 帧单独建“approach”样本。
3. 按 chunk=5 的边界采样，加入小动作噪声；验证训练/执行一致性。
4. 与基线比：同数据量、同算力下的单任务成功率。

**风险**：伪标签噪声；过采样导致过拟合；接触段任务不均衡。缓解：按任务分层；置信度低的样本降权；保留 20% 任务做 held-out。

### 3.6 I5 · COMPLIANCE-MODE HEAD（P2，模型侧）

**动机**：让 VLA 自己知道“现在该软还是该硬”，而不是所有任务都用同一组柔顺参数。

**与现有方案的差异**：
- CompVLA 预测连续刚度矩阵；本方案先做**离散模式分类 + 接触分数**，更容易用伪标签训练，也更适合 6Hz 外环。
- 辅助头挂在 WLA 的 DiT action expert 上，和动作头共享特征、同一个 checkpoint；不加载第二个策略，符合单模型规则。

**技术可行性**：WLA 微调只训 DiT + state projector；加一个 2 层 MLP 头即可；24GB 够。标签来自 I1/I6/I4。

**所需资源**：1×24GB GPU；官方 WLA Base；伪标签；2–3 周。

**落地步骤**：
1. 冻结 VLM，加载 WLA Base；在 DiT 隐状态上加 contact/mode/normal 三个头。
2. 联合损失：`L_action + λ1 BCE(contact) + λ2 CE(mode) + λ3 cosine(normal)`。
3. 先只训 contact/mode，确认不掉动作精度；再加 normal。
4. 消融：有头 vs 无头；头输出接柔顺 vs 固定模式。

**风险**：辅助头拖累动作头；伪标签偏差；单模型合规解释。缓解：小权重、早停、只训 DiT；提交材料写清楚“同一 checkpoint 的辅助头，不是第二模型”。

### 3.7 I6 · GRIPPER-AS-SENSOR（P1，极便宜）

**动机**：抓空/滑移是常见早期失败；Dex1 的夹爪位置反馈其实能告诉我们“夹住了没有、物体多宽、有没有滑”。

**做法**：
- `g_stall = a_g − s_g`；当命令继续闭合而实测停住，判定接触/夹住。
- 夹爪闭合速率突变→滑移；`s_g` 缓慢增大→物体被挤出。
- 位置式抓取力日程：先快速闭合到接触，再小步过闭（增加夹持力），最后回退一点（避免过力）；具体过闭量用单任务通道标定。
- 与 I1 融合：臂力影看“顶”，夹爪看“夹”。

**资源**：无需额外硬件；只需夹爪标定和少量 A/B。**风险**：夹爪内部控制器未知；物体变形/易碎；过闭可能损坏物体。缓解：保守过闭量；按任务限幅；易碎任务只用滞止检测，不加力。

### 3.8 I7 · HUMAN-EDIT RECOVERY（P2）

**动机**：人为干扰占 20% trials，是性价比最高的单项。第 11 轮 GEO-RESIDUAL 用视觉检测“场景动了，而且不是我的动作解释的”；本轮加力影：人推机器人/物体时，力影立即变化，比视觉更快。

**做法**：
- 视觉编辑分数 + 力影残差 + 夹爪滞止，三通道融合；阈值滞回。
- 检测到编辑：停→重定位桌面/受器→更新目标→保守增益恢复；目标不可见→VLA 重规划。
- 不声称 100%；只要求“检测≤200ms、恢复≥70%（仿真）”。

**风险**：人只是经过/遮挡导致误报；力影无法区分“人推”与“撞到固定物”。缓解：多帧确认；视觉/本体一致性；保守恢复。

### 3.9 I8 · EVAL-SLOT PORTFOLIO（P3，竞赛策略）

**动机**：挑战赛页面明确“预约评测时段”；正式 slot 稀缺。不能把 32 任务当无限次 A/B。

**做法**：
- 单任务通道做 5 任务 ×5 次 A/B；只有 ≥3/5 +10pp 才烧正式 slot。
- 正式评测优先 A 档接触任务；按 `q_t×Δ_t/cost_t` 排序。
- 若允许多次提交：先交安全基线锁“更早提交”tie-break，再交 FORCE-SHADOW。
- 若只允许一次：把唯一 slot 留给通过 G3 的版本；不要用正式评测做未验证的 A/B。
- 监控 `leaderboard_data.json` 与页面状态；页面 Coming Soon 可能是改版，不要误判为榜单重置。

### 3.10 剪枝/不做（本轮明确）

- **不做直接力矩控制**：API 没有 torque/current 动作；不要幻想“发 tau”。
- **不假设力传感器**：数据/接口都没有；所有力觉必须自监督。
- **不从零训 VLA/World Model**：官方 WLA 已 6B/2,500h/64 任务；算力不划算。
- **不让世界模型接管 30Hz 控制**：延迟/数据/单模型风险都高；世界模型最多做离线数据增强。
- **不做 32 任务各一个策略**：规则禁止，且不泛化。
- **不做 6D 物体位姿网络**：透明/反光/变形不可靠；用相对目标+局部几何+力影。
- **不做 30Hz 广域网伺服**：RTT 不允许；5 步 chunk/6Hz 外环是现实边界。
- **不把预览榜单任务排名当难度表**：已证伪；用自己的单任务数据。

## 4. 方法：FORCE-SHADOW 的系统拼图

### 4.1 总架构

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / 5-step chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)       │
                    │  ├─ table-frame estimator (stereo)  │
                    │  ├─ force-shadow estimator          │
                    │  ├─ compliance mode / C matrix      │
                    │  ├─ contact-anticipatory shaper     │
                    │  ├─ visual servo (CHUNK-SERVO)      │
                    │  └─ WLA adapter (54D rel → 21D abs) │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared VLA server (GPU)            │
                    │  UnifoLM-WLA-1.0 Base, 30-step      │
                    │  (+ optional compliance-mode head)  │
                    └─────────────────────────────────────┘
```

- **唯一学习策略**：WLA（或其轻微微调版）。
- **确定性控制器**：力影、桌面系、软件柔顺、chunk 整形、夹爪日程。
- **数据资产**：33k 演示 → 自由空间基线 + 接触伪标签；不是第二个策略。
- **仿真**：只做柔顺/延迟/扰动风洞，不训大模型。

### 4.2 力影的两条实现路径

**路径 A（最保守，推荐 MVP）：PD 刚度法**

```text
τ_hat[k] = kp ⊙ (q_cmd[k] − q_obs[k]) + kd ⊙ (dq_cmd[k] − dq_obs[k])
F_hat[k] = J(q_obs[k])^{-T} τ_hat[k]          # 6D wrench, base frame
F_hat_f  = lowpass(F_hat, fc)                  # fc ≈ 2–5 Hz
c        = ||F_hat_f − F_base|| / σ_F
n        = (F_hat_f − F_base) / (||...||+ε)
```

- `q_cmd` 来自上一段 chunk；`q_obs` 来自 5 帧状态历史；`dq` 用有限差分。
- `F_base` 是自由空间基线（重力/惯性/摩擦），离线拟合或在线用前几帧中位数。
- `kp/kd` 用 G1 官方示例或单任务通道标定；绝对力不准也能用方向/相对变化。

**路径 B（更强，但需要标定/辅助头）：EE 刚度法 / 学习残差**

```text
F_hat = K_x (x_cmd − x_obs) + K_r log(R_cmd R_obs^T)
```

- `K_x/K_r` 是低层 Cartesian 刚度；可用官方 PD 增益 + Jacobian 近似，或单任务通道标定。
- 学习残差：用 ridge/轻量 MLP 预测自由空间下一帧状态，残差当力影；只做离线基线和在线校正，不单独当策略。
- 若用 I5 辅助头，接触分数/法向由同一 WLA checkpoint 预测；力影仍保留为确定性兜底。

### 4.3 软件柔顺：用位置 API 实现“变刚度”

设 `x_nom` 是 VLA 的标称 EE 位姿，`F_hat` 是力影，`F_d` 是期望接触力，`C` 是柔顺矩阵（桌面系对角）：

```text
x_cmd = x_nom − C (F_hat − F_d)
```

低层 PD 的稳态关系近似 `F_ext = K_r (x_cmd − x)`，于是：

```text
F_ext = (I + K_r C)^{-1} K_r (x_nom − x) + (I + K_r C)^{-1} K_r C F_d
K_eff = (I + K_r C)^{-1} K_r
```

标量形式：`K_eff = K_r / (1 + K_r c)`。`c=0` 时刚；`c` 越大越软。方向性：`C = R diag(c_n, c_t, c_t, c_rn, c_rt, c_rt) R^T`，`R` 是桌面/接触系。

**稳定性**：`C` 半正定、外环 6Hz、内环 1kHz；加低通和能量罐：

```text
E_{k+1} = E_k + Δt (F_hat^T v − ε E_k)
if E_k < E_min: C ← 0.5 C
```

外环增益限幅：`||C K_r||_2 ≤ γ_max`；仿真扫 `γ_max ∈ [0.1, 2]`。6Hz + 延迟下，`γ_max` 通常要 <0.5；具体以仿真稳定域为准。

### 4.4 桌面坐标系

```text
T_base_table = [x_t, y_t, z_t, p_t]   # z_t = 桌面法向（朝上）
T_table_ee   = T_base_table^{-1} T_base_ee
F_table      = Ad_{T_table_base}^T F_base
C_table      = diag(c_x, c_y, c_z, c_rx, c_ry, c_rz)
```

- 插入/按压：`c_z` 大（软），`c_x/c_y` 小（硬）；拉链/拧：切向柔顺、法向硬。
- 桌面估计失败：回退 `T_base_table` 固定标定；置信度低时只做 base 系小增益柔顺。
- 非桌面任务（书架/传送带）：用受器局部坐标系替代桌面系；没有可靠平面就回退 base 系。

### 4.5 接触前 chunk 整形（固定 chunk 的“虚拟变长”）

```text
p = contact_probability (I1/I5)
if c > θ_c:          α = [1, 0, 0, 0, 0]       # 顶住：停/回退
elif p > 0.7:        α = [1, .5, .2, 0, 0]     # 预接触：快减速
elif p > 0.3:        α = [1, .8, .5, .3, .1]   # 接近：渐减速
else:                α = [1, 1, 1, 1, 1]       # 自由空间：全速
a'_k = a_0 + α_k (a_k − a_0)                    # 平移/旋转分别缩放
```

这样 chunk size 仍是 5，但“有效运动长度”随接触概率变短；不需要改 metadata，也不需要在 chunk 内重建观测。

### 4.6 状态机

```text
FREE ──p>0.1 / dist<5cm──▶ APPROACH ──c>θ_c──▶ CONTACT
  ▲                            │                  │
  │                            │                  ├─ mode=GRASP ──▶ GRASP
  │                            │                  ├─ mode=INSERT ─▶ INSERT
  │                            │                  └─ mode=PRESS ──▶ PRESS
  │                            │                                    │
  │                            └──────── RETRACT ◀── jam/force>Fmax ─┘
  │                                        │
  └──────────────── RECOVER ◀── human edit / force spike
任意状态 ──success/max steps──▶ DONE
```

- `FREE`：全速，视觉伺服主导。
- `APPROACH`：减速，力影+视觉融合；准备接触。
- `CONTACT`：法向软、切向硬；限力；检测顶死。
- `GRASP`：夹爪滞止→抓取成功；滑移→加力/重抓。
- `INSERT/PRESS`：法向柔顺+力目标；横向误差由视觉/力影方向修正。
- `RETRACT`：顶死/过力→回退 1–2cm，重对齐。
- `RECOVER`：人为编辑→停→重定位→重规划。

### 4.7 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 力影只离线生成接触标签；线上只有 VLA | 最低 | 保守备选 |
| C2 确定性控制器 | 力影/柔顺/桌面系/夹爪日程都是几何/控制律，无学习权重 | 低 | **主推 MVP** |
| C3 同 checkpoint 辅助头 | 接触/模式头挂在 WLA DiT 上，同一个 checkpoint | 低–中 | 第二阶段 |
| 禁止 | 第二个学习策略/残差网络/独立视觉编码器做在线决策 | 高 | 不做 |

## 5. 与第 10–12 轮的关系：保留、升级、剪枝

**保留**：
- FACT-VLA 的相位化 BC、CAC 柔顺执行、EGP 证据门控；
- GEO-RESIDUAL 的动作条件化残差、米制表面距离、编辑检测；
- CHUNK-SERVO 的 30 步规划 + 5 步执行、演示检索相对目标、轻量数字孪生、单任务通道。

**升级**：
- 视觉伺服 → 视觉 + 力影双环：视觉对孔，力影管顶/插/压；
- 开环 chunk → 接触前整形 + 软件柔顺：固定 chunk 内也能“减速/停/回退”；
- 绝对动作 → 桌面坐标系：法向/切向分解，位置/背景泛化更稳；
- 手工相位 → 残差/夹爪伪标签 + 可选辅助头：接触段自动加权；
- 单一大模型 → 一个学习模型 + 一个确定性力觉控制器（合规）。

**剪枝**：
- 不做直接力矩控制、力传感器假设、从零训 VLA/World Model、32 任务各一策略、6D 物体位姿网络、30Hz 广域网伺服；
- 不把预览榜单当难度表；
- 不在没有 G3 的情况下烧正式评测 slot。

## 7. 竞赛策略与预算

### 7.1 算术

- 总分 `S=(1/32)Σ p_t`；320 trials 下 `p≈0.25` 的单次标准误约 **2.42pp**；配对设计会低一些，但不要用 +1–2pp 下结论。
- 人为干扰轴 = 2/10 = **20%**；human 轴 +10pp → 全局 +2pp。
- 如果 10 个接触任务各 +10pp → `10/32×10=+3.1pp`；16 个各 +10pp → +5.0pp。
- 力影+柔顺+human 的保守目标 **+3–6pp**；乐观 +8pp+；必须用 G3/G8 证明。

### 7.2 任务组合（先验，待单任务通道更新）

- **P0 接触密集、力影杠杆最高**：PlugInEthernet、HangCup、ZipUp、StackBowls、PlugCharger、ArrangeTestTubes、Unlock、OpenPillBottle、StackCups、PaperCupStacking。
- **P1 抓取/放置/双手协调**：ToolboxStorage、PackBag、StoreRacket、StoreCups、StoreEarphones、PackPhone、OrganizePencilCase、SyringeWaterTransfer。
- **P2 变形/语义/长程**：FoldTowel、PackDoll、SpellRobot、ConveyorSorting、OrganizeBookshelf；力影不硬上，保留 VLA。
- **C 档**：单任务通道里 `p_t` 接近 0 且失败在早期感知/抓取的任务；不投力影工程。

优先级：`priority_t = q_t × Δ_t / cost_t`；`q_t` 先用语义先验，单任务后更新；先做 5 个，不要一次铺 19 个。

# 第 1 轮（新循环）产物 · FORCE-SHADOW 技术报告

> 检索/复核日期：**2026-10-29（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是想法区「FORCE-SHADOW」的工程化产物：把位置指令与实测位姿的残差变成 6D 力影，在桌面坐标系里做方向性软件柔顺和接触前 chunk 整形。它不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是把三者从“看得准、对得准”推进到“知道有没有顶住”。

## 0. 结论与边界

### 0.1 一句话结论

挑战赛 API 没有力/力矩/电流，但 G1 的位置控制内环一直在产生“跟踪误差”；把上一段 chunk 的位置目标与实测位姿之差乘以低层刚度，就得到一个无需额外硬件的 6D 力影。用这个力影在桌面坐标系里做“法向软、切向硬、接触前减速、顶死回退”，可以在不新增学习模型的前提下，把接触密集任务从位置开环变成力觉闭环。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、公开配置直接核实 | 规则、API 字段、33,276 eps、WLA `chunk_size=30`、G1 PD 公式 |
| B | 我们在公开数据/网页上做的分析，可复现 | 动作-状态残差在接触段放大 3–4 倍、夹爪滞止、榜单 `step~success` 回归 |
| C | 设计假设，需 G0–G8 验证 | AUROC≥0.80、柔顺 +10pp、6Hz 外环稳定、人为干扰恢复≥70% |

### 0.3 本轮不做什么

- 不做直接力矩控制：API 只接受位置目标，没有 torque/current 通道。
- 不假设机器人或数据带 F/T 传感器：33k 演示没有力列，线上观测也没有。
- 不从零训 VLA/World Model：官方 WLA 已是 6B、约 2,500 h、64 任务的基座。
- 不做第二个学习策略/残差网络：力影、桌面系、柔顺、chunk 整形都是确定性控制器。
- 不做 32 个任务各一个策略：规则要求同一模型，且不泛化。
- 不做 30Hz 广域网力控：RTT 不允许，现实外环是 5 步 chunk/约 6Hz。
- 不把预览榜单的任务排名当实测难度：第 12 轮已对 JSON 取证，本轮继续只当难度信号。
- 不在没有单任务 A/B 的情况下烧正式评测 slot：页面明确“预约评测时段”，slot 是稀缺资源。

### 0.4 与前三轮的关系

| 轮次 | 支点 | 本轮保留什么 | 本轮升级什么 |

提交模板 README（2026-10-29 复核）给出：

| 项 | 规格 |

**关键推论**：

1. `action_chunk_size=30`、30Hz 时一次调用后有 **1 秒开环执行**；chunk 内没有新观测，也没有打断机制。
2. 即使 `chunk=5`，执行块也有 **167ms**，外环约 **6Hz**；力控不可能靠“高频力矩环”，只能靠低层 PD 的 1kHz 内环 + 策略层 6Hz 的力影外环。
3. 这正好适配 FORCE-SHADOW：低层 PD 已经把“顶住”变成位置误差，我们只需要在外环读它，而不是发力矩。

### 1.5 G1 与 Dex1 的力相关事实（A）

- G1 低层手臂控制：

```math
\tau = k_p \odot (q_{des}-q) + k_d \odot (\dot q_{des}-\dot q) + \tau_{ff}.
```

- 官方示例手臂 `kp≈40–60`、`kd≈1–1.5`；不同关节/配置略有差异。
- Dex1-1：夹持力可调 **5–120 N**；电机状态反馈含角度、角速度、力矩、温度；控制指令支持角度、角速度、力矩、刚度、阻尼。但挑战赛 API 只给位置反馈和位置动作。**硬件有能力，接口没开放。**
- 可用信号：
  1. **臂的力影**：`τ_hat = kp⊙(q_cmd−q_obs)+kd⊙(dq_cmd−dq_obs)`，再用 `J^{-T}` 映射到 EE 6D wrench；或者直接在 `ee` 模式用 `F_hat = K_x(x_cmd−x_obs)`。
  2. **夹爪的滞止**：命令继续闭合而实测夹爪位置停住，说明夹住物体；`g_stall = a_g − s_g` 是抓取/滑移/物体宽度的代理。

## 2. 离线证据：动作-状态残差在接触段放大

### 2.1 数据与预处理

从官方数据抽两个单 shard（2026-10-29）：

| 任务 | 文件 | episodes | frames |
|---|---|---:|---:|
| HangCup | `G1_Dex1_HangCup/data/chunk-000/file-000.parquet` | 719 | 130,565 |
| PlugInEthernet | `G1_Dex1_PlugInEthernet/data/chunk-000/file-000.parquet` | 211 | 129,272 |

预处理：

1. 取双臂 14 维关节 + 2 维夹爪，共 16 维状态/动作。
2. 按 episode 分组，按帧时间排序；不跨 episode 拼接。
3. 动作使用数据中的目标列；状态使用同步的实测列。
4. 按 episode 归一化时间 `u∈[0,1]` 分 10 桶，避免长任务主导统计。
5. 只用前 30% 的中位残差做自由空间基线，算每个桶的 `ratio`。

### 2.2 方法

对每个时刻 `t`，用当前状态、当前动作、前 1/2 帧动作预测下一帧状态：

```math
\hat s_{t+1} = f_\theta(s_t, a_t, a_{t-1}, a_{t-2}),
\qquad
r_t = \|s_{t+1}-\hat s_{t+1}\|_2.
```

`f_θ` 是 ridge 线性回归（闭式解，CPU 可跑），不是神经网络。特征仅 16 维状态 + 3×16 维动作；每个任务单独拟合。残差 `r_t` 包含未建模动力学、摩擦、接触和传感器噪声，所以它只是**力影信号的存在性检验**，不是接触力真值。

夹爪滞止：

```math
e_g(t)=a_g(t)-s_g(t),\qquad
\mathrm{stall}(t)=\mathbb 1[e_g(t)>\epsilon_g].
```

`a_g` 是夹爪指令位置，`s_g` 是实测位置。`e_g` 大且持续，说明命令继续闭合但夹爪被物体挡住。

按归一化时间的残差 ratio（节选）：

|---|---:|---:|---:|

| HangCup | 0.4–0.5 | **3.02** | ≈0 |

互补性：

- 残差与夹爪误差的相关系数只有 **0.02（HangCup）/ −0.02（PlugInEthernet）**。

### 2.4 解释与局限

支持：

- 残差在 HangCup 的挂杯相位放大 3–4 倍，在 PlugInEthernet 的插拔/抓取相位放大 1.6–2.0 倍。
- 残差尖峰集中在接触相位，不是均匀分布；这符合“位置跟踪误差在受阻时变大”的物理直觉。
- 夹爪误差与臂残差几乎不相关，说明两个信号可融合，而不是重复。

局限（必须写进结论）：

- 单 shard，不是全量 33k；任务覆盖只有 2/32。
- 没有真值接触标签，无法算 AUROC；只能看相位对比。
- ridge 自由空间模型带 2–3 帧动作滞后，快速运动会被误判为残差。
- 残差混有未建模摩擦、重力、惯性、传感器噪声，不能直接当牛顿。
- 结论是“信号存在且可分”，不是“检测器已经可用”。

## 3. 问题形式化

### 3.1 评分与不确定性

总分：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

320 trials 下，若 `p≈0.25`，单次标准误：

```math
\mathrm{SE}(S)\approx \sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

配对 A/B 的方差取决于任务内相关；同初始条件配对可显著降低方差。报告必须给配对差值的 bootstrap 置信区间，不能只报两个平均值。

人为干扰轴：

```math
\Delta S_{\mathrm{human}} = \frac{2}{10}\,\Delta p_h = 0.2\,\Delta p_h.
```

human 轴 +10pp → 全局 +2pp。

### 3.2 力影定义

EE 模式（主路径）：

```math
\hat F_t = K_x\,(x^{cmd}_t-x^{obs}_t),
\qquad
\hat F_t \leftarrow \alpha \hat F_{t-1}+(1-\alpha)\hat F_t.
```

- `x_cmd` 是上一段 chunk 下发的绝对目标位姿；`x_obs` 是当前实测 EE 位姿。
- `K_x` 是低层 Cartesian 刚度；可用官方 PD 增益 + Jacobian 近似，或用单任务通道标定。
- `α` 由截止频率决定：`α=exp(-2π f_c Δt)`，`f_c≈2–5Hz`。

关节模式（备选）：

```math
\hat\tau_t = k_p\odot(q^{cmd}_t-q^{obs}_t)+k_d\odot(\dot q^{cmd}_t-\dot q^{obs}_t),
\qquad
\hat F_t = J(q^{obs}_t)^{-T}\hat\tau_t.
```

自由空间基线：

```math
\tilde F_t = \hat F_t - F^{base}_t,
\qquad
F^{base}_t = \mathrm{median}(\hat F_{t-k:t}).
```

接触分数与方向：

```math
c_t = \frac{\|\tilde F_t\|}{\sigma_F},
\qquad
n_t = \frac{\tilde F_t}{\|\tilde F_t\|+\epsilon}.
```

- `σ_F` 用自由空间残差分布的标准差/ MAD 标定。
- `c_t` 不是概率；接触判定用双阈值滞回：`c>θ_on` 进入接触，`c<θ_off` 退出。
- 方向 `n_t` 只在 `c_t` 足够大时使用；否则用桌面法向/接近方向兜底。

法向/切向分解（桌面系）：

```math
f_n = n_t^\top \tilde F_t,\qquad
f_t = (I-n_t n_t^\top)\tilde F_t.
```

### 3.3 软件柔顺

设 `x_nom` 是 VLA 的标称 EE 位姿，`F_hat` 是力影，`F_d` 是期望接触力，`C` 是柔顺矩阵：

```math
x_{cmd}=x_{nom}-C(\hat F-F_d).
```

低层 PD 的稳态关系近似 `F_ext=K_r(x_cmd-x)`，于是：

```math
F_{ext}=(I+K_r C)^{-1}K_r(x_{nom}-x)+(I+K_r C)^{-1}K_r C F_d,
```

```math
K_{eff}=(I+K_r C)^{-1}K_r.
```

标量形式：

```math
K_{eff}=\frac{K_r}{1+K_r c}.
```

`c=0` 时刚；`c` 越大越软。方向性：

```math
C=R\,\mathrm{diag}(c_n,c_t,c_t,c_{rn},c_{rt},c_{rt})\,R^\top,
```

`R` 是桌面/接触系到 base 系的旋转。插入/按压：`c_n` 大（软），`c_t` 小（硬）；拉链/拧：切向柔顺、法向硬。

### 3.4 稳定性

外环 6Hz、内环 1kHz，且存在 RTT。简化离散误差模型：

```math
e_{k+1}=e_k-K H_c\,e_{k-d},
```

`d=τ/(H_c/f_c)` 是延迟块数。特征方程：

```math
z^{d+1}-z^{d}+K H_c=0.
```

- `d=0`：稳定域 `0<KH_c<2`。
- `d=1`：稳定域 `0<KH_c<1`；增益裕度约减半。
- `d=2`：稳定域更小；必须降增益或加预测。

工程约束：

```math
\|C K_r\|_2\le \gamma_{max},\qquad \gamma_{max}\in[0.1,0.5].
```

再加低通和能量罐：

```math
E_{k+1}=E_k+\Delta t\,(\hat F_k^\top v_k-\epsilon E_k),
\qquad
E_k<E_{min}\Rightarrow C\leftarrow 0.5C.
```

仿真扫 `τ∈{0,50,100,150}ms`、`H_c∈{3,5,8}`、`γ_max∈{0.1,0.2,0.5,1.0}`，只允许在稳定域内上真机。

### 3.5 桌面坐标系

```text
T_base_table = [x_t, y_t, z_t, p_t]   # z_t = 桌面法向（朝上）
T_table_ee   = T_base_table^{-1} T_base_ee
F_table      = transform_wrench(T_base_table, F_base)
C_table      = diag(c_x, c_y, c_z, c_rx, c_ry, c_rz)
```

- `z_t` 由头部双目点云 + 工作区 RANSAC 平面估计；`x_t` 用 base x 投影或桌沿方向。
- 估计失败或置信度低 → 回退固定标定或 base 系小增益柔顺。
- 非桌面任务（书架/传送带）用受器局部坐标系；没有可靠平面就回退 base 系。

### 3.6 接触前 chunk 整形

固定 chunk 不能变长，但可以变“运动包络”：

```text
p = contact_probability
if c > θ_c:          α = [1, 0, 0, 0, 0]       # 顶住：停/回退
elif p > 0.7:        α = [1, .5, .2, 0, 0]     # 预接触：快减速
elif p > 0.3:        α = [1, .8, .5, .3, .1]   # 接近：渐减速
else:                α = [1, 1, 1, 1, 1]       # 自由空间：全速
a'_k = a_0 + α_k (a_k - a_0)
```

性质：

- chunk size 仍是 5，但有效运动长度随接触概率变短。
- 不需要改 metadata，也不需要在 chunk 内重建观测。
- `α` 对平移和旋转分别缩放；旋转缩放更保守（`α_r=0.5α_p`）。
- 顶死时 `[1,0,0,0,0]` 之后 evaluator 仍执行剩余零运动步，相当于保持/等待下一个观测。

### 3.7 可辨识性与回退

力影只在以下条件同时满足时参与控制：

1. 任务属于刚体接触类（插入/挂/叠/压/拉链/锁/拧）。
2. `||\tilde F||` 超过自由空间噪声门限，且持续 ≥2 帧。
3. 桌面/受器法向估计置信度足够；否则只用各向同性小增益。
4. 夹爪/腕部没有明显遮挡力影的异常（如线缆缠绕）。
5. 没有检测到人为编辑/碰撞导致的突变。

任一条不满足 → 回退 VLA 开环或仅视觉伺服；不硬做力控。

## 4. 系统设计

### 4.1 进程/端口拓扑

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / 5-step chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)       │
                    │  ├─ table-frame estimator (stereo)  │
                    │  ├─ force-shadow estimator          │
                    │  ├─ compliance mode / C matrix      │
                    │  ├─ contact-anticipatory shaper     │
                    │  ├─ visual servo (CHUNK-SERVO)      │
                    │  └─ WLA adapter (54D rel → 21D abs) │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared VLA server (GPU)            │
                    │  UnifoLM-WLA-1.0 Base, 30-step      │
                    │  (+ optional compliance-mode head)  │
                    └─────────────────────────────────────┘
```

- 唯一学习策略：WLA（或轻微微调版）。
- 确定性控制器：力影、桌面系、软件柔顺、chunk 整形、夹爪日程。
- 数据资产：33k 演示 → 自由空间基线 + 接触伪标签；不是第二个策略。
- 仿真：只做柔顺/延迟/扰动风洞，不训大模型。

### 4.2 每端口 `get_action` 伪代码

```python
class ForceShadowPolicy:
    def get_action(self, obs):
        self._tick(obs)
        self._maybe_request_plan(obs)

        if self.plan is None:
            self.plan = self.vla.predict(obs)
            self.plan_idx = 0

        a_ff = self.plan[self.plan_idx : self.plan_idx + self.H_c]
        if len(a_ff) < self.H_c:
            a_ff = np.pad(a_ff, ((0, self.H_c - len(a_ff)), (0, 0)), mode="edge")

        F_hat, c, n = self.force.update(
            x_cmd=self.last_cmd, x_obs=obs.ee_pose, q_cmd=self.last_q,
            q_obs=obs.q, dq_obs=obs.dq, t=obs.t)

        frame = self.table.update(obs.stereo, obs.ee_pose)
        mode = self.mode_machine.update(c, self.gripper.stall(obs), frame)

        if self.enabled and mode in CONTACT_MODES:
            a_ff = self.compliance.apply(
                a_ff, F_hat, mode, frame, self.C[mode], self.F_d[mode])
            a_ff = self.shaper.apply(a_ff, c, mode)

        out = self.adapter.to_api(a_ff, obs, self.token)
        self.last_cmd, self.last_q = out.cmd, out.q
        self.plan_idx += self.H_c
        if self.plan_idx >= len(self.plan):
            self.plan = None
        return out
```

规则：

- VLA 不阻塞 `get_action`（除冷启动）；plan 过期就用旧 plan + 力影/视觉修正。
- 每个 chunk 只做一次力影更新；力影失败不影响返回合法动作。
- 任何异常 → 返回上一组合法 chunk 或安全 hold；绝不返回 NaN/错误形状。
- 每个端口独立 `ForceShadowPolicy`、独立 `reset()`、独立状态机；共享的只有只读基线和权重。

### 4.3 力影实现路径

**路径 A（MVP，推荐）：EE 刚度法**

```text
F_hat = K_x (x_cmd - x_obs)
F_base = median(F_hat[t-15:t])
F_tilde = lowpass(F_hat - F_base, fc=3Hz)
c = ||F_tilde|| / sigma_F
n = F_tilde / (||F_tilde|| + eps)
```

- 只需要目标位姿和实测位姿；`K_x` 用官方 PD + Jacobian 近似或单任务标定。
- 绝对力不准也能用方向/相对变化；接触判定用双阈值滞回。

**路径 B（更强，但需标定）：关节力矩法**

```text
tau_hat = kp * (q_cmd - q_obs) + kd * (dq_cmd - dq_obs)
F_hat = J(q_obs)^{-T} tau_hat
```

- `kp/kd` 用 G1 官方示例；`J` 用 URDF 或数值差分。
- 需要处理重力/摩擦/惯性基线；适合有 URDF 和关节速度的部署。

**路径 C（辅助，不单独当策略）：学习残差**

```text
F_hat = K_x (x_cmd - x_obs) + g_phi(s, a, history)
```

- `g_phi` 是 ridge/轻量 MLP，只用官方数据训练，预测自由空间下一帧状态；残差作校正。
- 若用 I5 辅助头，接触分数/法向由同一 WLA checkpoint 预测；力影仍保留为确定性兜底。

### 4.4 夹爪日程

```text
g_stall = a_g - s_g
if g_stall > eps and closing:
    contact = True
    g_cmd = s_g + close_margin        # 小幅过闭，增加夹持力
elif slipping(g_stall, s_g):
    g_cmd = min(g_cmd + slip_step, g_max)
else:
    g_cmd = a_g
```

- `close_margin`/`slip_step` 按任务标定，保守起步。
- 易碎/变形任务只用滞止检测，不加过闭。
- 夹爪信号与臂力影融合：臂看“顶”，夹爪看“夹”。

### 4.5 状态机

```text
FREE ──p>0.1 / dist<5cm──▶ APPROACH ──c>θ_c──▶ CONTACT
  ▲                            │                  │
  │                            │                  ├─ mode=GRASP ──▶ GRASP
  │                            │                  ├─ mode=INSERT ─▶ INSERT
  │                            │                  └─ mode=PRESS ──▶ PRESS
  │                            │                                    │
  │                            └──────── RETRACT ◀── jam/force>Fmax ─┘
  │                                        │
  └──────────────── RECOVER ◀── human edit / force spike
任意状态 ──success/max steps──▶ DONE
```

| 状态 | 力影/柔顺 | 视觉 | 退出条件 |
|---|---|---|---|
| FREE | 关闭 | 视觉伺服主导 | 接近目标/接触概率上升 |
| APPROACH | 小增益，准备 | 减速、对孔 | `c>θ_on` |
| CONTACT | 法向软、切向硬 | 局部修正 | 进入 GRASP/INSERT/PRESS |
| GRASP | 夹爪滞止→加力 | 物体随动 | 抓稳/滑移 |
| INSERT/PRESS | 力目标 + 限力 | 轴向对齐 | 完成/顶死 |
| RETRACT | 回退 1–2cm | 重对齐 | 重新接近 |
| RECOVER | 停/降增益 | 重定位/重规划 | 恢复或放弃 |

### 4.6 WLA adapter（54D 相对 → 21D 绝对）

挑战赛 `ee` 动作是 2×6 EE + 2×1 gripper + 7 pivot = **21 维**；WLA 是 **54 维**统一动作。映射：

1. `left_ee_abs = compose(T_base_ee_left_current, exp(left_ee_rel))`；转 xyz+rpy。
2. `right_ee_abs` 同理。
3. gripper 直通（按挑战赛 0–1 方向校验）。
4. `pivot` 从 WLA base/waist/height 组合；具体符号/顺序必须用 `example_env.py` 和单任务通道验证。
5. 腿部/灵巧手在挑战赛 `ee` 模式下不直接下发；若 `pivot` 需要下身体，按官方 WLA server 的语义映射。

关键细节：WLA 的每个未来动作是“相对 plan-time 当前 EE”的位姿，不是累积增量；adapter 必须先把整个 30 步 compose 成 base 系绝对目标，再按 5 步切片。否则第 6–30 步会以错误锚点解释，产生系统性偏移。

帧/TCP 风险：WLA 的 EE 帧与挑战赛 `*_ee_pose_gripper_base` 可能差一个 TCP/夹爪长度偏移；必须用 `example_env.py` 观测和真实数据做一次工具坐标校准（平移 ≤1cm、旋转 ≤2°）。`pivot` 语义不明确时先返回全零 pivot，只验证双臂。

### 4.7 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 力影只离线生成接触标签；线上只有 VLA | 最低 | 保守备选 |
| C2 确定性控制器 | 力影/柔顺/桌面系/夹爪日程都是几何/控制律，无学习权重 | 低 | **主推 MVP** |
| C3 同 checkpoint 辅助头 | 接触/模式头挂在 WLA DiT 上，同一个 checkpoint | 低–中 | 第二阶段 |
| 禁止 | 第二个学习策略/残差网络/独立视觉编码器做在线决策 | 高 | 不做 |

## 5. 数据引擎与训练

### 5.1 接触中心的重采样

33k 演示里大部分帧是自由空间；接触段只占少数，但决定成败。标准 BC 对接触段欠采样，训练帧与 5 步执行也不一致。

管线：

1. 全量计算 `r_t`（残差）、`e_g(t)`（夹爪误差）、可选腕部接触分数。
2. 按 episode 归一化时间 + 信号阈值生成 `contact_score∈[0,1]`。
3. 训练采样权重 `w=1+3·contact_score`；接触前 5 帧单独建 `approach` 样本。
4. 按 chunk=5 的边界采样，加入小动作噪声模拟执行漂移。
5. 按任务分层，保留 20% 任务做 held-out；相邻帧不跨 split。

### 5.2 接触模式辅助头

- 挂在 WLA 的 DiT action expert 上，共享特征，同一个 checkpoint。
- 输出：`contact`（BCE）、`mode`（FREE/APPROACH/GRASP/INSERT/PRESS/RETRACT，CE）、`normal`（cosine）。
- 损失：`L = L_action + λ1 BCE + λ2 CE + λ3 cosine`；先只训 contact/mode，确认不掉动作精度，再加 normal。
- 标签来自 I1/I6/I4 的伪标签；人工抽查 200 帧校准。
- 只训 DiT + state projector，冻结 VLM；24GB 够。

### 5.3 数据泄漏与评估

- 按 episode/session/物体/背景分组划分；同一演示的相邻帧不能跨 train/val。
- 目标库检索评估也要按 session 划分，不能把同一 episode 的相邻帧当独立样本。
- 离线 AUROC 只用于筛信号，不预测真机成功率；真机必须单任务 A/B。

## 7. 竞赛策略与预算

### 7.1 算术

- `S=(1/32)Σp_t`；320 trials 下 `p≈0.25` 的单次标准误约 **2.42pp**；配对设计会低一些，但不要用 +1–2pp 下结论。
- 人为干扰轴 = 2/10 = **20%**；human 轴 +10pp → 全局 +2pp。
- 10 个接触任务各 +10pp → `10/32×10=+3.1pp`；16 个各 +10pp → +5.0pp。
- 力影+柔顺+human 的保守目标 **+3–6pp**；乐观 +8pp+；必须用 G3/G8 证明。

### 7.2 任务组合（先验，待单任务通道更新）

- **P0 接触密集、力影杠杆最高**：PlugInEthernet、HangCup、ZipUp、StackBowls、PlugCharger、ArrangeTestTubes、Unlock、OpenPillBottle、StackCups、PaperCupStacking。
- **P1 抓取/放置/双手协调**：ToolboxStorage、PackBag、StoreRacket、StoreEarphones、PackPhone、OrganizePencilCase、SyringeWaterTransfer。
- **P2 变形/语义/长程**：FoldTowel、PackDoll、SpellRobot、ConveyorSorting、OrganizeBookshelf；力影不硬上，保留 VLA。
- **C 档**：单任务通道里 `p_t` 接近 0 且失败在早期感知/抓取的任务；不投力影工程。

优先级：

```text
priority_t = q_t × Δ_t / cost_t
```

`q_t` 先用语义先验，单任务后更新；先做 5 个，不要一次铺 19 个。

## 8. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 力影被滞后/摩擦污染 | 误报接触 | 自由空间基线；只用相对变化/方向；融合夹爪/视觉 |
| 绝对力标定不准 | 力目标偏差 | 不追求绝对牛顿；用相对柔顺；单任务标定 |
| 6Hz 外环振荡 | 插入失败/碰撞 | 小 `C`；低通；能量罐；仿真稳定域；降增益 |
| 单模型解释 | 被判第二模型 | C2 确定性控制器；C3 同 checkpoint 辅助头；提交材料写清楚 |
| 桌面平面估计错 | 法向偏 | 固定标定回退；多帧 RANSAC；置信度门控 |
| 透明/反光/变形 | 力影/视觉失败 | 只对刚体任务启用；易碎/变形任务降权/关闭 |
| 夹爪内部控制器未知 | 抓取力日程失效 | 保守过闭；滞止检测；单任务标定 |
| WLA adapter/pivot 不一致 | 机器人不动/动作被拒 | `example_env.py` 验证；零 pivot 回退；先单任务 |
| 评测 slot 稀缺 | 没机会迭代 | 单任务 A/B；安全基线先锁；不烧未验证版本 |
| 榜单预览 | 过拟合 | 不从任务排名挖点；用自己的数据 |
| 数据泄漏 | 离线虚高 | 按 episode/session/物体/背景分组；相邻帧不跨 split |
| 安全 | 碰撞/过力 | 限速/限幅/最大重试；力影超阈值即停/回退 |

## 10. 一句话押注

**最值得押注的是 FORCE-SHADOW + COMPLIANT-CHUNK：用位置指令与实测位姿的残差当“力传感器”，在桌面坐标系里对 5 步 chunk 做“法向软、切向硬、接触前减速、顶死回退”的软件柔顺；它不需要额外硬件、不违反单模型规则，而且直接对准 32 个任务里最难的接触段。**
