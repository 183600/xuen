# 第 5 轮 · RUBICON 5.0：把数字孪生从“渲染器”降级为“标注器 + 反事实发生器”

> 检索/复核日期：2026-10-24。先确认：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），不是其他同名 UniBot。以下所有分数只作难度先验；公开榜仍是占位。

## 0. 本轮先核实：两个前提被修正

### 0.1 数据集不是“小样本”，而是“完整 33k”

上一轮我记录的是 HangCup 44 条、ArrangePlates 115 条、OrganizeStationery 341 条，并据此判断“数据少、要省着用”。本轮复核发现这是旧 collection 的预览计数/旧版本：新 collection `unibot-v1-challenge-dataset` 里 HangCup 已经 1,043 条、194,564 帧；StackBowls 979 条、295,609 帧；32 个任务基本都在 970–1,530 条之间，合计约 33k 条、169 小时。[S6][S7][S8][S27] 官方页的 32,000/169h 现在与 HF 一致。[S3]

这个修正很重要：**数据量已经不是主要瓶颈**。真正的瓶颈是数据“不够杂”——公开数据是名义演示，而评测 10 次全部是泛化条件。手册写得很清楚：每个任务 10 次，5 类泛化各 2 次；没有“名义条件”这一项。[S4] 也就是说，模型在评测中永远不会遇到训练分布的原点。上一轮把重点放在“单模型 + 谓词残差”是对的，但缺少一个按测试分布造数据的引擎。

### 0.2 官方仿真栈已经齐了

- `unitree_sim_isaaclab`：G1-29dof-Dex1、与真机相同的 DDS、数据回放、`--generate_data` 通过改光照/相机参数批量生成数据；代码 Apache-2.0。[S9]
- `unitree_lerobot`：LeRobot v3、`eval_g1_sim.py`、`Unitree_G1_Dex1_Sim` 数据类型；Apache-2.0。[S10]
- `unitree_mujoco`：G1 23/29 DoF MJCF、sim2sim；BSD-3。[S11]
- `lerobot/unitree-g1-mujoco`：G1 + Dex1 的 MuJoCo 模型，带头/双腕相机；资产许可需逐个核。[S12]

这意味着“从零搭一个 G1 数字孪生”不再是主要工作量。真正缺的是 **UniBot 32 个任务的场景、相机/桌面/物体标定、五轴反事实配方、以及合成数据的 gap filter**。这是本轮要补的薄层。

### 0.3 榜单仍是占位，不能拿分数做决策

`leaderboard.html` 仍显示“即将发布 / Coming Soon”；`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`；8 个模型、榜首 MolmoAct2 29.7%、WALL-OSS 28.5%、DreamZero 27.9%。[S1][S2] 这组数字与用户简报“榜首不到 30%”一致，但它是占位数据，不是真实排名。它能提供的只有“难度先验”：如果真实分布也接近这个量级，说明大多数模型在泛化轴上掉得很厉害。我们不能用它反推谁强谁弱。

### 0.4 两个许可证事实

- `UnifoLM-WLA-1.0-Base` 是 Apache-2.0，6B、约 2,500 小时、64 任务，官方文档说 action-expert 微调默认面向单卡 24GB。[S13][S14][S25] 继续做主底座。
- `UnifoLM-WMA-0` 是 CC BY-NC-SA 4.0，虽然它自带“simulation engine / policy enhancement”能力，但不能进主路径；最多做离线神经仿真，且要先过法务。[S15]

## 1. 三个灵感词，这次怎么用

### 1.1 数字孪生：不要做“更真的图”，要做“更准的标签”

第一反应是建一个高保真仿真，渲染几十万条数据训练。这条路在 2026 年有很多正面证据：SimFoundry 用单视频重建数字孪生，object/scene/task cousins 分别带来 +17%/+21%/+40% 真机成功率，仿真评测与真机的 Pearson 相关 0.911；DREAM 用 real2sim + TAMP 给预训练 VLA 生成微调数据；ARSTAG 从单图 + 语言生成数据，π0.5 真机平均 74.6%；PhyVisGen 只用合成数据在 5 个真机任务上做到 65–95%。[S16][S17][S18][S19]

但这些工作大多是刚体桌面、平行夹爪、静态场景；UniBot 有布料（毛巾）、拉链、透明试管/手机、插头/网线、人为干扰。**直接照搬“渲染大量数据”会在最难的轴上翻车**。所以本轮把孪生的角色拆成三个：

1. **标注器（Twin Label Engine, TLE）**：对真实 episode 做重建，输出物体 6D 位姿、部件 mask、接触事件、谓词状态（`grasped/inserted/folded/zipped/...`）、谓词持续时间、undo 事件。真实图像分布不变，只是多了密集标签。这是 sim2real gap 最小的用法。
2. **反事实发生器（Axis Counterfactual Pairs, ACP）**：以真实 episode 为锚，只改变一个官方泛化轴，生成配对样本。价值在“配对”，不在单张图；用配对做不变/等变/恢复损失，比单纯堆数据更省样本。
3. **本地评测台（Twin-Calibrated Local Bench, TCLB）**：32 任务 × 5 轴 × 2 次的本地评测，只用于相对比较和失败挖掘；用 6 个任务 × 5 轴 × 2 次的真机子集校准，报告相关性，不把仿真分数当榜单预测。

一句话：**孪生不进推理，只进数据和评测。**

### 1.2 开源生态：做集成商，不做重复建设

上一轮已经确定 WLA 是主底座；本轮不换底座，也不重造仿真器。栈是：

| 层 | 选择 | 许可 | 用途 |
|---|---|---|---|
| 数据 | `G1_Dex1_*` LeRobot v3 | Apache-2.0 | 32 任务、约 33k episodes |
| 底座 | `UnifoLM-WLA-1.0-Base` 6B | Apache-2.0 | G1 域内先验、action expert |
| 训练 | `unifolm-wla` / `unitree_lerobot` | Apache-2.0 | LoRA/action expert、LeRobot 策略 |
| 仿真 | `unitree_sim_isaaclab` | Apache-2.0（资产另核） | G1-29dof-Dex1、DDS、回放、生成 |
| 快速物理 | `unitree_mujoco` / `lerobot/unitree-g1-mujoco` | BSD-3 / 资产另核 | sim2sim、MJCF、相机 |
| 资产 | TableVerse / RoboCousin / Objaverse / ABO | 混合 | 物体、背景、数字表亲 |
| 部件教师 | SAM3 / PartSAM | 逐个核 | 离线伪标签 |
| 神经仿真 | `UnifoLM-WMA-0` | CC BY-NC-SA | 仅离线、P2、法务先过 |
| 评测 | `eval_g1_sim.py` | Apache-2.0 | 本地 32 任务评测起点 |

这张表的意义：**我们只写 UniBot 特有的一层**——任务场景、标定、五轴配方、gap filter、轴损失。其余全部复用。这样 8 周才有可能做完。

### 1.3 虚拟仿真：按 ROI 分桶，不搞“全任务高保真”

仿真不是越多越好。按“仿真能否提供可信的动作/物理”分三桶：

- **A 类（全孪生）**：刚体抓放、堆叠、排序、摆放。T02/T04/T06/T07/T08/T13/T15/T20/T21/T22/T25/T27。仿真可以提供位姿、堆叠稳定性、放置区域、遮挡；适合位置/干扰物/背景/未见物品四轴。
- **B 类（几何/接触标签 + 接近轨迹）**：接触密集、铰接、公差小。T01/T05/T09/T10/T12/T14/T23/T26/T28/T29/T30/T32。仿真只信“几何、部件、接触事件、接近方向”，不把插入/倒出的成功当监督；动作仍以真实轨迹为锚。
- **C 类（2.5D 编辑 + 真实回放）**：布料、拉链、透明、动态、杂物。T03/T11/T16/T17/T18/T19/T24/T31。不做全物理；只做背景替换、干扰物叠加、物体外观替换、人手 overlay，动作直接复用真实轨迹。

这个分桶是本轮最重要的修剪。不做全 32 任务的高保真孪生，也不做布料/拉链的物理仿真。

## 2. 本轮主判断：测试是 100% 泛化，数据引擎必须按轴设计

### 2.1 一个简单的算术

10 次评测 = 5 轴 × 2，每轴 64 次（32 任务 × 2），总 320 次。总分是 5 轴成功率的平均：

```text
S = (s_position + s_distractor + s_background + s_unseen + s_human) / 5
ΔS = Δs_axis / 5
```

所以：

| 改进 | 总分增益 |
|---|---:|
| 某一轴 +10pp | +2.0pp |
| 某一轴 +15pp | +3.0pp |
| 某一轴 +20pp | +4.0pp |
| 某一轴 +25pp | +5.0pp |
| 五轴各 +5pp | +5.0pp |

320 次试验在 p≈0.3 时 SE≈2.56pp；+3pp 约等于 80% 概率排名更高，+5pp 约等于 90%。[S4] 所以**先修最弱的一轴，比在每个任务上抠 1pp 划算得多**。

### 2.2 假设：头部模型不是输在名义，而是输在弱轴

占位榜的 29.7% 不能当真实成绩，但可以当假设：如果模型在位置/干扰物上还行（比如 40–50%），在背景/未见物品/人为干扰上很差（比如 10–20%），那么平均就会被拉到 30% 左右。此时把 human 从 10% 提到 30%，总分 +4pp；把 unseen 从 20% 提到 40%，再 +4pp。两个轴就 +8pp，足以显著改变排名。这个假设必须用**覆盖审计 + 轴诊断矩阵**验证，不能直接当真。

### 2.3 为什么必须是“真实锚定”

自由仿真数据有两个致命问题：

- **视觉漂移**：渲染的光照/材质/相机与真机不一致，模型学到仿真纹理。
- **物理漂移**：接触刚度、摩擦、变形、透明折射不对，动作标签在真机上不可执行。

真实锚定把这两个问题压到最小：

- 每条合成 episode 都从一条真实 episode 的初始状态/关键帧出发；
- 只改变一个轴，动作轨迹用真实轨迹做重定向/重规划，不做自由探索；
- 用 gap filter 给每个样本打权重，低权重样本不参与或只参与辅助损失；
- 在真实 held-out episode 上早停，绝不用仿真成功率做模型选择。

## 3. TS-GPR：把孪生接进 GPR-VLA

上一轮的 GPR-VLA 是：

```text
语言 l → Goal Compiler → z*
4 视图 + proprio → Part Encoder → b
r = z* − b
Action Expert → chunk + horizon + duration
```

本轮不推倒，只在三个位置加孪生监督：

```text
                   ┌──────────── Twin (offline) ────────────┐
                   │  TLE: poses/parts/contact/predicates  │
                   │  ACP: 5-axis counterfactual pairs     │
                   │  RB:  undo/intervention recovery      │
                   └───────────────┬───────────────────────┘
                                   │ labels / pairs / weights
                                   ▼
语言 l → Goal Compiler → z* ─┐
4 视图 + proprio → Part Encoder → b ─┼→ r = z* − b → Action Expert → chunk/h/d
                                   │
                          Belief Tracker (reversible)
```

三个新件：

1. **TLE（Twin Label Engine）**：给真实帧补 dense labels。真实帧的物体位姿由重建 + PnP 得到，部件 mask 由 SAM3/PartSAM + 孪生投影得到，接触/谓词由孪生状态机得到。置信度低的帧降权。
2. **ACP（Axis Counterfactual Pairs）**：五轴配对。背景/干扰物 → 动作不变性；位置 → 动作等变性；未见物品 → affordance 对比 + 动作重规划；人为干扰 → 恢复目标。配对样本共享同一条真实锚，训练信号是“相对关系”，不是“绝对外观”。
3. **RB（Recovery Bank）**：把官方 `human_1/human_4` 的干扰动作做成原语库（推、抬、转、拿走、挡住、undo），在真实/孪生轨迹的随机时刻注入，生成“破坏 → 恢复”对。直接训练 GPR-VLA 的 `b: 1→0→1` 可逆信念。

再加两个工程件：

4. **GF（Gap Filter）**：视觉/物理/动作/语义四类 gap 的软权重，见 §5。
5. **TCLB（Twin-Calibrated Local Bench）**：32×5×2 本地评测，见 §7。

## 4. 任务分桶与五轴配方

### 4.1 分桶

| 桶 | 任务 | 孪生角色 | 不做什么 |
|---|---|---|---|
| A（12） | T02/T04/T06/T07/T08/T13/T15/T20/T21/T22/T25/T27 | 全孪生：位姿、堆叠、放置、遮挡 | 不追求照片级；用真实背景纹理 |
| B（12） | T01/T05/T09/T10/T12/T14/T23/T26/T28/T29/T30/T32 | 几何/部件/接触标签 + 接近轨迹 | 不把插入/倒出成功当监督 |
| C（8） | T03/T11/T16/T17/T18/T19/T24/T31 | 2.5D 编辑 + 真实回放 | 不做布料/拉链/透明物理 |

### 4.2 五轴配方

| 轴 | 怎么造 | 标签 | 损失 | 主要风险 |
|---|---|---|---|---|
| 位置 | 平移目标物体/目标区域；真实 EE 轨迹重定向 + IK | 新位姿、新轨迹 | 动作 flow + 位置等变 | 不可达、碰撞、遮挡 |
| 干扰物 | 从资产库插入 1–5 个杂物；避让目标与机器人 | 干扰物 mask；目标谓词不变 | 动作不变 + 部件对比 | 遮挡目标、改变语义 |
| 背景 | 换桌布/墙面/光照；C 类用 2D 合成 | 无 | 动作不变 + 特征一致 | 光影不真实 |
| 未见物品 | 同 affordance、不同颜色/形状/材质；重规划抓取 | 新部件 mask/位姿 | 动作 flow + affordance 对比 | affordance 不匹配 |
| 人为干扰 | 按官方备注注入推/抬/转/拿走/挡住/undo | 事件、状态、恢复动作 | 恢复 + 信念可逆 | 人手外观/动作不真 |

### 4.3 一个具体例子：T27 StackBowls

- 真实锚：979 条，295,609 帧；三只碗，堆叠，human_4 是“拿走第二个碗”。[S8]
- A 类全孪生：三只碗的位姿、堆叠稳定性、桌面高度都能标定。
- 位置轴：平移三只碗的初始布局，重定向抓取/放置轨迹。
- 干扰物轴：加筷子/杯子/纸巾，目标碗不变。
- 背景轴：换桌布颜色/纹理，加阴影。
- 未见物品轴：换不同直径/颜色的碗，重规划抓取。
- 人为干扰：在第二只碗放好后拿走它，生成“重新放回”的恢复轨迹。
- 验收：在孪生里 100 条反事实，gap filter 通过率 >50%；训练后真机/仿真至少一个轴 +10pp。

## 5. Gap Filter：合成数据的“闸门”

四个分数：

```text
d_vis  = 最近邻 DINOv2 距离（同任务、同阶段真实帧）
d_phys = 穿透/不稳定/关节超限/接触冲量/非物理跳变
d_act  = 锚点帧动作与真实重定向动作的归一化差 + 平滑/加加速度
d_sem  = 1 − 孪生任务成功 + 谓词一致性惩罚
w = clip(exp(−(α d_vis + β d_phys + γ d_act + δ d_sem)), 0.1, 1.0)
```

- 软权重，不硬删；低权重样本只参与辅助损失或不参与。
- 阈值在真实 held-out 上校准；通过率 <30% 说明孪生还没准备好，退回 labels-only。
- 每个任务/轴分别校准，不用全局阈值。

## 6. 训练配方

- 数据混合：真实 100% + 合成 20–50%（按轴/任务），弱轴过采样；合成不能主导。
- 损失：动作 flow matching + 谓词 BCE + 部件 mask/centroid + 轴不变/等变 + 恢复 + 少量孪生一致性。
- 课程：真实基线 → TLE 标签 → 背景/干扰物 → 位置 → 未见物品 → 恢复 → 全量。
- 早停：真实 held-out + 轴诊断矩阵；不看仿真成功率。
- 防遗忘：每批混真实；任务平衡采样；监控最差轴。
- 算力：WLA action expert 单卡 24GB 可跑；8×H100 1–2 周做全量/LoRA；孪生标注 8 卡 2–4 天（先 6 任务）。

## 7. 本地评测台 TCLB

- 32 任务 × 5 轴 × 2 次 = 320 episodes；180s；同 API。
- A/B 类用孪生；C 类用真实回放 + 2.5D 编辑。
- 真机校准子集：T02/T04/T10/T16/T20/T27 × 5 轴 × 2 次 = 60 trials。
- 指标：sim-real Pearson/Spearman、MAE、排序保持、每轴成功率、恢复成功率、time-to-complete。
- 使用门槛：相关 >0.7 且 MAE <10pp 才用于 A/B 决策；否则只做失败挖掘。
- 绝不把 TCLB 分数写进提交材料当真实成绩。

## 9. 风险与停止条件

- **外部数据/仿真是否允许**：手册 1.1–2.2 没有明确禁止，但也没说允许；先发邮件问 `challenge_support@unitree.com`，同时做 `labels_only / counterfactuals / full` 开关。若禁止，退回 SAM3/PartSAM + 纯真实数据。
- **标定失败**：相机重投影 >5px、桌面 >5mm、物体位姿 >1cm、回放 EE >2cm，任一不达标就先修标定，不进训练。
- **gap 太大**：通过率 <30% 或真实验证掉 >2pp，退回 labels-only。
- **负迁移**：合成比例降到 10–20%，只保留弱轴；仍不行就停。
- **集成成本**：先 MuJoCo（轻）后 Isaac（重）；Docker 锁版本；先 1 个任务再 6 个。
- **许可**：WMA-0 离线且法务过；资产逐个登记 SPDX；模型卡写清数据来源。
- **统计**：320 trials，SE≈2.56pp；目标 +3pp 才值得上线；用配对种子/bootstrap。

### 1.3 评分算术

设五轴成功率为 `s_p, s_d, s_b, s_u, s_h`：

```text
S = (s_p + s_d + s_b + s_u + s_h) / 5
```

若只改一轴：

```text
ΔS = Δs_axis / 5
```

| 单轴提升 | 总分提升 | 直观含义 |
|---:|---:|---|
| +5pp | +1.0pp | 小修小补 |
| +10pp | +2.0pp | 值得做 |
| +15pp | +3.0pp | 明显改变排名 |
| +20pp | +4.0pp | 强 |
| +25pp | +5.0pp | 很强 |

每轴 64 trials，二项分布 SE = sqrt(p(1−p)/64)。p=0.3 时 SE≈5.73pp（单轴），总分 SE≈2.56pp；p=0.5 时单轴 SE≈6.25pp，总分≈2.80pp。所以**单轴 +10pp 在 64 trials 下并不总是显著**，需要配对种子/多轮复核。

## 2. 问题定义与失败模型

### 2.1 为什么头部也只有约 30%

假设（待验证）：名义成功率可能 50–70%，但五轴平均被 2–3 个弱轴拉到 30%。典型失败：

1. **位置轴**：目标平移后，抓取点/放置点不重规划；开环 chunk 直接撞空。
2. **干扰物轴**：目标被遮挡或语义混淆；模型抓错物体。
3. **背景轴**：纹理/光照变化导致视觉编码漂移；部件分割不稳。
4. **未见物品轴**：affordance 不匹配；抓取姿态沿用训练类别。
5. **人为干扰轴**：被推/被拿走/被挡住后，模型继续执行旧计划；不会撤销/重试。

### 2.2 五轴失败分类（用于诊断矩阵）

| 轴 | 观测 | 根因假设 | 对应组件 |
|---|---|---|---|
| 位置 | 抓空、放偏、碰撞 | 等变性差、无重规划 | ACP-position、GPR 残差 |
| 干扰物 | 抓错、遮挡后停 | 目标 grounding 弱 | ACP-distractor、部件对比 |
| 背景 | 分割抖、抓取点漂 | 视觉过拟合 | ACP-background、特征一致 |
| 未见物品 | 抓不住、不会换姿态 | affordance 不泛化 | ACP-unseen、重规划 |
| 人为干扰 | 旧计划继续、不复位 | 无恢复策略、信念不可逆 | RB、可逆 Belief Tracker |

### 2.3 现有方法 gap

| 方法族 | 代表 | 强项 | 在 UniBot 的 gap |
|---|---|---|---|
| 端到端 VLA | π0.5、GR00T、WLA | 通用、易微调 | 泛化轴无显式监督；干扰后不恢复 |
| 3D 策略 | 3D Diffuser Actor、RISE | 空间泛化 | 依赖深度/点云；透明/布料弱 |
| 数据增强 | ROSIE、GenAug | 便宜 | 2D 增强不改变物理/接触 |
| Real2Sim | SimFoundry、DREAM、ARSTAG | 数据规模 | 多为刚体/平行夹爪；C 类不适用 |
| 世界模型 | WMA-0、DreamZero | 预测/规划 | 许可/延迟/漂移；单模型合规 |
| 残差/谓词 | GPR-VLA（上一轮） | 可解释、对准评分 | 缺密集标签与反事实 |

**本方案的差异化**：不追求“更真的仿真”，而是追求“更准的轴标签 + 配对反事实 + 可逆恢复”，并且把孪生限制在离线。

## 3. TS-GPR 架构

### 3.1 总览

```text
┌──────────────────────────── Offline ────────────────────────────┐
│  Real episodes (33k)                                            │
│      │                                                          │
│      ├─► TLE: reconstruction + PnP + SAM3/PartSAM + twin state  │
│      │        → poses, part masks, contact, predicates, undo    │
│      │                                                          │
│      ├─► ACP: 5-axis counterfactual pairs                       │
│      │        position / distractor / background / unseen / human│
│      │                                                          │
│      ├─► RB: intervention primitives + recovery trajectories    │
│      │                                                          │
│      └─► GF: d_vis, d_phys, d_act, d_sem → sample weights       │
│                                                                 │
│  Output: augmented dataset D_aug + labels + weights             │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────── Training ───────────────────────────┐
│  l → Goal Compiler → z*                                         │
│  4 views + proprio → Part Encoder → b                           │
│  r = z* − b → Action Expert → (chunk, horizon, duration)        │
│  Belief Tracker (reversible): b_t, predicate state, undo flag   │
│  Losses: flow + predicate + part + axis-inv/equiv + recovery    │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────── Inference ──────────────────────────┐
│  Single checkpoint, single process per port                     │
│  No simulator, no world model, no MPC in the loop               │
│  N ports from 8765, health/metrics/logs                         │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 GPR-VLA backbone（沿用上一轮）

- **Goal Compiler**：语言 + 任务 ID + 物体检测 → 谓词目标 `z*`（如 `grasped(cup) ∧ on(cup, coaster)`）。谓词表来自 32 任务 `info.json` 的阶段描述。
- **Part Encoder**：4 视图（头 + 双腕 + 可选外部）→ 部件 token；输出部件信念 `b`（存在、位姿、可见性、接触）。
- **Residual Head**：`r = z* − b`，把“还差什么”显式化；动作专家以 `r` 为条件。
- **Action Expert**：flow matching 输出 chunk、horizon、duration；AH-TP 用谓词时长监督。
- **Belief Tracker**：可逆状态机；支持 `undo` 事件；干扰后回退到上一个稳定谓词。

### 3.3 TLE：Twin Label Engine

**目标**：给真实帧补密集标签，不改变图像分布。

步骤：

1. **标定**：相机内参/外参、桌面平面、机器人基座；重投影误差 <5px，桌面 <5mm。
2. **重建**：对每个任务的关键物体做 CAD/扫描/资产匹配；用 FoundationPose/BundleSDF 类方法估计 6D 位姿；用 SAM3/PartSAM 得部件 mask。
3. **跟踪**：视频级位姿平滑；遮挡用孪生投影补；置信度低于阈值置零。
4. **事件**：接触（EE-物体、物体-物体、物体-桌面）、谓词状态、持续时间、undo。
5. **输出 schema**：

```json
{
  "episode_id": "hangcup_000123",
  "frame": 42,
  "objects": [{"id": "cup_1", "pose": [x,y,z,qw,qx,qy,qz], "part": "handle", "conf": 0.91}],
  "contact": [{"a": "gripper", "b": "cup_1", "type": "grasp", "conf": 0.88}],
  "predicates": {"grasped(cup_1)": true, "on(cup_1,hook)": false},
  "events": [{"t": 41, "type": "contact_start"}],
  "undo": false
}
```

**质量门槛**：位姿误差 <1cm、部件 mask IoU >0.7、谓词一致率 >90%；不达标的任务退回 2D 标签。

### 3.4 ACP：五轴反事实配对

每条合成样本都绑定一条真实锚 `(e, t0)`；只改一个轴：

| 轴 | 生成 | 保留 | 监督 |
|---|---|---|---|
| 位置 | 平移目标/目标区域；EE 轨迹重定向 + IK | 物体、背景、语言 | 动作等变、位置残差 |
| 干扰物 | 插入 1–5 个杂物；避让目标/机器人 | 目标、语言、背景 | 动作不变、部件对比 |
| 背景 | 换桌布/墙/光照；C 类 2D 合成 | 物体、动作、语言 | 特征一致、动作不变 |
| 未见物品 | 同 affordance 新颜色/形状/材质 | 任务、目标谓词 | affordance 对比、重规划 |
| 人为干扰 | 注入推/抬/转/拿走/挡住/undo | 场景、目标 | 恢复、信念可逆 |

**配对损失**：

```text
L_pair = λ_inv * ||f(o_a) − f(o_b)||²            # 背景/干扰物：动作不变
       + λ_eq  * ||π(o_a) − T(π(o_b))||²          # 位置：动作等变
       + λ_aff * max(0, m − ||f(o_u) − f(o_neg)||²) # 未见物品：affordance 分离
       + λ_rec * ||a_rec − a*||²                   # 干扰：恢复动作
```

其中 `f` 是部件/视觉特征，`π` 是动作 chunk，`T` 是已知平移变换。

### 3.5 RB：Recovery Bank

- 原语：`push`, `lift`, `rotate`, `take_away`, `block`, `undo`。
- 来源：官方 `human_1/human_4` 备注 + 真实回放中的人工干预片段 + 孪生注入。
- 生成：在真实轨迹的稳定谓词后随机注入原语，记录 `b: 1→0`；再用重规划/回放生成 `b: 0→1` 的恢复段。
- 训练：恢复段单独加权；推理时由 Belief Tracker 的 `b` 下降触发重规划，不依赖外部分类器。
- 安全：恢复动作限速/限幅；连续失败 2 次进入安全姿态。

### 3.6 GF：Gap Filter

```text
d_vis  = 1 − cos(DINOv2(I_syn), DINOv2(I_real_nn))
d_phys = penetration + instability + joint_limit + impulse + teleport
d_act  = ||a_syn − a_real|| / ||a_real|| + jerk + smoothness
d_sem  = (1 − task_success_sim) + predicate_inconsistency
w = clip(exp(−(α d_vis + β d_phys + γ d_act + δ d_sem)), 0.1, 1.0)
```

- 分任务/分轴校准阈值；不用全局阈值。
- 通过率 <30% → 该任务退回 labels-only。
- 低权重样本：只参与辅助损失，或不参与。
- 每 2 周用真实 held-out 重新校准一次。

### 3.7 TCLB：Twin-Calibrated Local Bench

- 规模：32 × 5 × 2 = 320 episodes；180s；与官方 API 一致。
- A/B 类：孪生；C 类：真实回放 + 2.5D 编辑。
- 真机校准子集：T02/T04/T10/T16/T20/T27 × 5 轴 × 2 = 60 trials。
- 指标：每轴成功率、恢复成功率、time-to-complete、sim-real Pearson/Spearman、MAE、排序保持。
- 门槛：相关 >0.7 且 MAE <10pp 才用于 A/B 决策；否则只做失败挖掘。
- 禁止：把 TCLB 分数写进提交材料当真实成绩。

### 3.8 SAP：Simulability-Aware Portfolio

上一轮 Task Portfolio 按“分数 × 成本”分配；本轮加“可仿真性”：

```text
priority(t) = marginal_gain(t) * simulability(t) / cost(t)
simulability(t) ∈ {full, labels, 2.5D}
```

- A 类：full，优先做背景/干扰物/位置。
- B 类：labels，优先做部件/接触/接近。
- C 类：2.5D，优先做背景/干扰物，不做物理。
- 预算：孪生 40%、训练 35%、真机/评测 25%。
- 停止：某任务连续两轮无增益，降到 labels-only。

### 4.2 标定

- 相机：棋盘/ArUco + 手眼标定；重投影 <5px。
- 桌面：平面拟合 + 高度；误差 <5mm。
- 机器人：URDF/MJCF 与真机对齐；EE 回放误差 <2cm。
- 物体：资产库匹配 + 6D 位姿；误差 <1cm。
- 时间：DDS 时间戳对齐；偏移 <10ms。

### 4.3 A 类 pipeline（12 任务）

```text
real episode → scene graph → twin scene → axis edit → trajectory retarget/IK
→ render → gap filter → paired sample
```

- 场景：桌面、物体、目标区域、机器人。
- 轴编辑：位置（平移）、干扰物（插入）、背景（材质/光照）、未见物品（替换）、人为干扰（原语）。
- 轨迹：真实 EE 轨迹 + 相对变换；IK 失败则丢弃。
- 渲染：IsaacLab；每任务先 200 条试点。

### 4.4 B 类 pipeline（12 任务）

- 只用孪生做：物体位姿、部件 mask、接触事件、接近方向、间隙/公差。
- 不做：插入成功、倒出成功、铰接成功等物理结果监督。
- 动作：真实轨迹锚定 + 小范围重定向；不做自由探索。
- 适用：插头/网线、透明试管、手机、铰接物体、精密放置。

### 4.5 C 类 pipeline（8 任务）

- 布料/拉链/透明/动态/杂物：不做全物理。
- 2.5D 编辑：背景替换、干扰物叠加、物体外观替换、人手 overlay。
- 动作：直接复用真实轨迹；只改视觉上下文。
- 目的：提升背景/干扰物/人为干扰轴的鲁棒性，不声称物理孪生。

### 4.6 生成规模（首轮）

| 桶 | 任务 | 每任务/轴 | 轴数 | 样本 |
|---|---:|---:|---:|---:|
| A | 12 | 200 | 5 | 12,000 |
| B | 12 | 100 | 3 | 3,600 |
| C | 8 | 100 | 3 | 2,400 |
| 合计 | 32 | — | — | 18,000 |

通过 GF 后预计 50–70%，即 9k–12.6k 可用；相对 33k 真实数据是 27–38%，符合“合成不主导”的原则。

## 5. 训练

### 5.1 损失

```text
L = L_flow + λ1 L_pred + λ2 L_part + λ3 L_axis + λ4 L_rec + λ5 L_twin + λ6 L_reg
```

| 项 | 作用 | 权重（起始） |
|---|---|---:|
| L_flow | 动作 chunk flow matching | 1.0 |
| L_pred | 谓词 BCE / 状态机一致性 | 0.2 |
| L_part | 部件 mask/centroid/可见性 | 0.1 |
| L_axis | 不变/等变/affordance 配对 | 0.1 |
| L_rec | 恢复动作 | 0.2 |
| L_twin | 孪生标签一致性（仅 A/B） | 0.05 |
| L_reg | 参数正则/LoRA | 1e-4 |

### 5.2 课程

| 阶段 | 数据 | 目标 | 退出条件 |
|---|---|---|---|
| 0 | 真实 100% | 复现 WLA 基线 | 真实 held-out 不降 |
| 1 | 真实 + TLE 标签 | 谓词/部件更稳 | 谓词 F1 +5 |
| 2 | + 背景/干扰物 | 视觉鲁棒 | 两轴各 +5pp（TCLB） |
| 3 | + 位置 | 空间等变 | 位置 +5pp |
| 4 | + 未见物品 | affordance | unseen +5pp |
| 5 | + 恢复 | 干扰恢复 | human +5pp |
| 6 | 全量 + 蒸馏 | 单模型稳定 | 无轴掉 >2pp |

### 5.3 超参（起始）

- 底座：WLA-1.0-Base 6B；LoRA rank 64 / alpha 128；action expert 全量或 LoRA。
- 优化器：AdamW，lr 1e-4（LoRA）/ 2e-5（全量），cosine，warmup 3%。
- batch：global 64–128（视显存）；grad checkpointing。
- 序列：4 视图 + proprio + 语言；历史 1–2 帧。
- 动作：chunk 16–32，horizon 1–2s，duration head。
- 精度：bf16；DeepSpeed/FSDP 视规模。
- 早停：真实 held-out + 轴诊断；patience 2 轮。

| 项 | 规格 | 时间（估） |
|---|---|---|
| TLE 标注（6 任务试点） | 8×H100 | 2–4 天 |
| TLE 标注（32 任务） | 8×H100 | 1–2 周 |
| 生成 18k 样本 | 8×H100 | 3–5 天 |

## 6. 评测

### 6.1 TCLB 协议

1. 固定 32 任务、5 轴、每轴 2 次、180s。
2. 每 episode 固定随机种子；记录初始状态、物体位姿、干扰事件。
3. 成功判定与官方一致；步骤分单独记录。
4. 每轮跑 320 episodes；至少 2 个种子。
5. 输出：`results.csv` + 每轴成功率 + 失败视频 + 失败分类。

### 6.2 真机校准

- 子集：T02/T04/T10/T16/T20/T27（覆盖 A/B/C）。
- 60 trials；与 TCLB 同种子/同初始状态。
- 计算 Pearson/Spearman/MAE/排序保持。
- 相关 <0.7 或 MAE >10pp：TCLB 只做失败挖掘，不做模型选择。
- 每 2 周重校准；记录漂移。

### 6.3 统计

- 主指标：五轴平均成功率。
- 次指标：每轴成功率、恢复成功率、time-to-complete、步骤分。
- 置信：bootstrap 1,000 次；配对种子；报告 95% CI。
- 多重比较：Bonferroni 或 FDR；避免“挑最好种子”。
- 决策：+3pp 且 CI 不跨 0 才上线；否则回滚。

- 每轮真实 held-out 与 TCLB 同时跑。

- 记录每任务/轴的“合成增益/真实增益”散点。

## 9. 风险、合规与开关

### 9.1 风险表

| 风险 | 概率 | 影响 | 缓解 | 停止条件 |
|---|---|---|---|---|
| 外部数据/仿真被禁 | 中 | 高 | 邮件确认；`labels_only` 开关；纯真实回退 | 明确禁止 → 停 ACP/GF |
| 标定不达标 | 中 | 高 | 先 MuJoCo 后 Isaac；分阶段验收 | 重投影 >5px 或 EE >2cm → 不训练 |
| 视觉 gap 大 | 高 | 中 | 真实背景/纹理；GF；低权重 | 通过率 <30% → labels-only |
| 物理 gap 大 | 高 | 中 | B/C 类不做物理监督 | 仿真成功与真实不符 → 只信几何 |
| 负迁移 | 中 | 高 | 合成 ≤50%；混真实；早停 | 真实掉 >2pp → 减半/停 |
| 任务冲突 | 中 | 中 | SAP；分桶；最差轴监控 | 某任务掉 >5pp → 单独回退 |
| 恢复不安全 | 中 | 高 | 限速/限幅；两次失败安全姿态 | 安全测试失败 → 关闭 RB |
| 许可风险 | 低 | 高 | 只用 Apache-2.0/BSD-3；WMA 离线；SPDX | 许可不清 → 不用 |
| 单模型审计 | 中 | 高 | 所有决策进一个 checkpoint；规则式安全 | 审计不通过 → 去辅助模型 |
| 统计噪声 | 高 | 中 | 320 trials；配对种子；bootstrap；多轮 | CI 跨 0 → 不上线 |
| 部署不稳 | 中 | 高 | N 端口；健康检查；4h soak；回滚 | 漂移 >10pp → 先修部署 |
| 时间不够 | 中 | 高 | 先 6 任务；先 labels；砍 C 类 | W6 未达 M3 → 缩范围 |

### 9.2 合规开关

```yaml
data_policy:
  mode: labels_only | counterfactuals | full   # 默认 labels_only，邮件确认后升级
  external_sim: false                          # 默认关；确认后开
  external_pretrained: true                    # WLA Apache-2.0
  wma_offline: false                           # CC BY-NC-SA，默认关
  provenance_log: true                         # 每条样本记录来源
  license_manifest: true                       # SPDX/NOTICE
```

- **单模型**：推理只加载一个 checkpoint；TLE/ACP/GF 全部离线；安全 monitor 是规则式，不是第二个模型。
- **数据来源**：真实数据 Apache-2.0；合成数据由我们生成，标注来源与许可；不混入 NC 数据。
- **资产**：逐个登记 SPDX；Isaac 资产许可单独核；不用来源不明资产。
- **安全**：参考 ISO 10218-2:2025 的风险评估思路；不声称认证；限速/限幅/急停。
- **提交**：模型卡写清数据、训练、评测、已知限制；保留 NOTICE；不引用占位榜分数。
