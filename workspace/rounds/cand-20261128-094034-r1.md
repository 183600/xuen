### 第 7 轮灵感驱动研究记录

**灵感词**：用户需求分析、大语言模型、面部表情识别

**继承关系**：第 6 轮 CADVS-v6（IP-497~IP-500）确立「指令-几何-力学三元凿」框架：GGC 提供抓取几何可达性约束、MCTM 注入空间拓扑图、STM 实现跨模态指令-轨迹映射，七硬门保持 fail-closed 边界。本轮延续「硬门不增」原则，聚焦「**需求-意图-一致性三角桥**」：在保持证书边界不变的前提下，直接从「用户需求分析」出发，设计「需求意图建模器」(DIM)，引入「需求一致性软评分」η_demand，使系统从「被动接受指令」转向「主动推导意图」。

**直觉与动机**：

1. **用户需求 → 从「指令响应」到「意图推导」**。第 6 轮的 STM 负责「语言→查询向量」的映射，但它无法区分「用户真正想要的」与「用户不够清晰说出的」。引入「需求意图建模器」(Demand Intent Model, DIM)：从用户的历史交互记录、当前环境约束、任务目标三方面推断「用户真正的需求目标」ρ_demand。关键洞见是：**行为从「指令驱动」转向「需求驱动」**——只有当推断的需求意图与指令意图高度一致时，才执行STM生成的轨迹；否则，触发「需求导向回退」。

2. **大语言模型 → 从「静态映射」到「动态推理」**。第 6 轮的 STM 采用 CLIP-style 对齐训练，对指令进行向量化。第 7 轮引入「需求推理链」(Demand Reasoning Chain, DRC)：将LLM连接到DIM，使得从「用户说了什么」到「用户可能需要什么」的推理过程可解释、可审计。关键洞见是：**LLM 充当「需求解释器」**——它的推理链被量化为 η_demand，若推理置信度低于阈值，系统自动切换到历史记忆中的「典型需求响应」。

3. **面部表情识别 → 从「情感调制」到「需求态度捕获」**。第 6 轮的 FAMK 调制阈值 γ_i。第 7 轮提出「需求态度捕获」(Demand Affect Capture, DAC)：基于面部表情识别，捕获用户当前的「需求态度」(desire_affect)——如焦虑表情可能意味着「需要快速、稳妥的解决方案」，而放松表情可能意味着「愿意探索创新方案」。关键洞见是：**情感态度调制需求优先级**——DAC 输出的 desire_affect 调节 ρ_demand 的稀疏性和探索度。

**关键洞见**：第 6 轮回答「如何在不新增硬门的前提下，让提议符合物理、空间、意图」；第 7 轮回答「如何从「用户需求」出发，让系统主动推导「正确的行为」，而不是被动接受指令」。七硬门 kc_evidence_forged_v5 记号原样复用；本轮新增的只有：
- IP-501 DIM（需求意图建模器），
- IP-502 DRC（需求推理链，LLM驱动），
- IP-503 DAC（需求态度捕获），
- IP-504 EFA-v7（软评分 η_demand 纳入四软因子链）

**形式化目标（增量）**：

1. **DIM（Demand Intent Model）**：<br>
   - 需求编码器 E_demand: (history, context, env) ⟼ ρ_demand ∈ ℝ^d_demand<br>
   - 损失 L_DIM = ||ρ_demand - ρ_gold||² + β·KL(π_demand || π_prior)<br>
   - 软因子：η_demand = 1 - H(ρ_pred || ρ_demand)，其中 H 为交叉熵<br>
   - 只有当 η_demand > τ_demand 时，STM 输出的指令才被采纳；否则触发「需求导向回退」

2. **DRC（Demand Reasoning Chain）**：<br>
   - LLM 推理链 R = {r_1, r_2, ..., r_n}，其中 r_i 为推理步骤<br>
   - η_demand = 1 - (1/n)·Σ_i H(r_i)，衡量推理链的整体确定性<br>
   - L_DRC = α·链长度惩罚 - η_demand，鼓励简洁且确定的推理

3. **DAC（Demand Affect Capture）**：<br>
   - 表情编码器 E_affect: face ⟼ affect ∈ {-1, 0, +1}（负面/中性/正面）<br>
   - desire_affect 调节 ρ_demand 的探索度：exploration_scale = 1 + κ·affect<br>
   - 软因子：η_affect = 1 + affect/3 ∈ [2/3, 4/3]，调制 STM 检索的广度

4. **EFA-v7（七硬门 + 四软因子链）**：<br>
   - ECS_v7 = ECS_v6 · η_g · η_topo · η_interp · η_cmd · η_demand · η_affect<br>
   - τ_i^v7 = γ_i·τ_i^v6·Π_factor_i，其中 Π_factor_i = ∏_{j=1}^5 η_j ∈ [1, 1+ε]，设计上限仍为 1.3<br>
   - 新增硬门 kc_demand：η_demand ≥ τ_demand，确保「用户需求」被必要检验

5. **形式化定义**：给定指令 L，目标 ρ_target，记忆 M：<br>
   - ρ_demand = DIM(history, context, env)；<br>
   - η_demand = 1 - H(STM(L) || ρ_demand)；<br>
   - 若 η_demand < τ_demand：<br>
     - q_demand = E_demand(ρ_demand)；<br>
     - m_demand = Top-k(Retr_M(q_demand, K=4))；<br>
     - c_demand = (obj, g_emb, θ_fp, task, ŝ_emo, m_demand, ρ_target, t_topo, q_demand)；<br>
     - x_demand = FMPP.propose(c_demand, K=8)；<br>
   - 若 η_demand ≥ τ_demand：<br>
     - 执行第 6 轮的 EFA-v6 流程<br>

**直觉与动机（本轮迭代扩展）**：

1. **碰撞检测 → 从「硬门约束」到「需求驱动碰撞 guard」**：现有七硬门保证 fail-closed，但未在需求导向回退路径中引入几何碰撞检测。关键洞见：**需求推断的轨迹若存在几何碰撞，即便一致性 η_demand 高，也应拒绝或触发安全回退**。引入 η_collision 软因子，基于 GGC 碰撞网格实时评估 x_demand 与环境的碰撞概率。

2. **语义地图 → 从「向量近似」到「结构化语义映射」**：当前 DIM 的 ρ_demand ∈ ℝ^d_demand 仅作为稠密向量，缺乏语义结构化表征。关键洞见：**引入语义地图，将 ρ_demand 投射到任务语义簿，通过 k-NN 检索确保 ρ_demand 与实际可达任务的语义一致性**，从而 η_demand 有了结构化依据而非纯统计近似。

3. **痛点分析 → 从「假设致盲」到「三层防护机制」**：核心风险是用户意图的非线性突变与自我否定。痛点分析指向三层防护：① **Dual-track DIM**（主需求路径 + 备选路径，经一致性投票），② **η_demand 实时可解释性检查**（每一步 η_demand 的变化趋势而非单点阈值），③ **需求演化检测**（连续 3 轮 η_demand 变化率超过阈值时强制回退）。

**关键洞见**：第 7 轮已回答「如何主动推导正确行为」；本轮迭代回答「如何在推导过程中 guards 多维度防止『正确但有风险』的行为」；七硬门依然保持 fail-closed，新增的只有软因子扩展与两层防护机制。

**形式化目标（增量）**：

1. **η_collision（碰撞软因子）**：
   - 基于 GGC 碰撞网格：η_collision = 1 - (碰撞体素计数 / 总体素数) ∈ [0,1]
   - 仅在需求导向回退路径中计算；常规 EFA-v6 流程不受影响

2. **语义地图投射**（Semantic Map Projection，SMP）：
   - S(ρ_demand) = Top-k(Retr_M(q_semantic, K=8))，其中 q_semantic = W·ρ_demand + b 为可学习投影
   - 一致性验证：η_semantic = 1 - (1/k)·Σ_j sim(ρ_demand, ρ_target_j)，sim 为余弦相似度
   - 若 η_semantic < τ_semantic（默认 0.6），触发语义一致性回退

3. **Dual-track DIM**：
   - 主路径：ρ_demand^main = DIM.encode(history, context, env)
   - 备路径：ρ_demand^alt = DIM.encode(history_tail, context, env) 其中 history_tail 为最近 3 条交互
   - 投票：若 sim(ρ_demand^main, ρ_demand^alt) > τ_vote（默认 0.7），则使用主路径；否则使用备路径并标记「需求不稳定」

4. **EFA-v7 增强**：
   - ECS_v7 = ECS_v6 · η_g · η_topo · η_interp · η_cmd · η_demand · η_affect · η_collision
   - 软因子链 Π_factor_i = ∏_{j=1}^7 η_j ∈ [1, 1.3]（已含 η_collision，设计上限 1.3 保持不变，意味着 η_collision 默认置 1 或在常规流程中不计）

5. **形式化定义（增量）**：
   - ρ_demand = DIM(history, context, env)；<br>
   - （主路径）ρ_demand^main = ρ_demand；<br>
   - （备路径）ρ_demand^alt = DIM(history_tail, context, env)；<br>
   - η_semantic = 1 - (1/k)·Σ_j sim(ρ_demand, ρ_target_j)；<br>
   - η_collision = 1 - (collision_voxels / total_voxels)；<br>
   - 若 η_demand < τ_demand  或  η_semantic < τ_semantic  或  η_collision < τ_collision（默认 0.5）：<br>
     - 走需求导向回退，并额外检查 η_collision<br>
   - 若 所有 软因子 ≥ 阈值：<br>
     - 执行 EFA-v6 在线流程 + 软因子链 × η_demand × η_affect × η_collision

**本轮最大风险**：**需求意图的非线性突变与自我否定**：尽管引入 dual-track 与语义地图，但用户意图仍可能在短期内发生非线性突变（如 suddenly switching from「放置到桌子」到「拿走到柜子」），此时 dual-track 可能因历史权重过大而滞后，语义地图的投影投影也可能过旧。这种结构上的捕获难题在维持七硬门 fail-closed 边界时，仍可能导致「正确但时机不当」或「正确但错误目标」的行动。

### 第 8 轮灵感驱动研究记录

**灵感词**：分布外泛化、长期记忆

**继承关系**：第 7 轮 CADVS-v7（IP-501~IP-504）在七硬门之外引入 DIM/DRC/DAC 与六项软因子链，把系统从「指令响应」推进到「需求推导」。但第 7 轮留下一个未解的结构性缺口：软因子链越接越长（η_g·η_topo·η_interp·η_cmd·η_demand·η_affect），却始终没有回答「**系统凭什么相信自己在一个没见过的情境里仍然可以行动**」。本轮直接以「分布外泛化」与「长期记忆」这对灵感词互补作答：把 OOD 从「密度模型的新颖性异常」重构为「**记忆是否提供了可证书化的支撑**」，并用保形预测（conformal prediction）给出无分布假设的有限样本支撑度 η_ood。核心原则仍是「硬门不增」：OOD 的 fail-closed 边界折叠进既有新颖性硬门（Ψ_novel / kc_evidence_forged_v5），不新增第八道硬门。

**直觉与动机**：

1. **分布外泛化 → 从「拒绝新奇」到「向记忆质询新奇是否可支撑」**。直觉：一位厨师遇到没见过的食材不会立刻停手，而是回忆「我处理过类似质地的东西，那次成功了」。第 7 轮把 OOD 交给流策略密度模型（R53），密度在联合高维空间里既不可靠又无保证。本轮改为：对查询 x，在长期记忆案例库中找 k 个近邻，用这些近邻自身的非一致性分数构造**保形支撑度** η_ood。关键洞见：**OOD 不是要被软因子抹平的缺陷，而是要被记忆认证的边界条件**。

2. **长期记忆 → 从「向量仓库」到「带来源与遗忘的案例库」**。直觉：永不遗忘的记忆终将变成噪声，任意遗忘的记忆又会丢掉 OOD 锚点。第 7 轮的 lmem 只是嵌入检索；本轮升级为 LMC-v2：每条案例保留 (context, action, outcome, evidence, provenance, weight)，用「验证成功则强化、长期未验证则衰减、低权重则淘汰」的整合算子维持一个有界、可审计、可漂移检测的案例库。关键洞见：**记忆的价值不在于「存了多少」，而在于「能否为当下的外推提供可追溯的锚」**。

3. **OOD × 记忆 → 三区制分派，泛化发生在「插值区」**。把支撑度划成三区：内分布区走 EFA-v7 原流程；**插值区**用「案例基泛化器」（CBG）把检索到的已认证锚作为流匹配的条件，在锚的认证邻域内生成轨迹——这才是「分布外泛化」的真实机制：不盲目外推，而是在已证书化的锚之间插值；**外推区**（真 OOD）fail-closed，只允许保守脚手架动作或主动求助。关键洞见：**泛化不是把 OOD 当内分布处理，而是承认外推区并把它交给人类/保守策略**。

4. **保形预测 → 把「支撑」变成可检验的量**。η_ood 不是拍脑袋的 softmax 置信度，而是基于 k-NN 非一致性分数的保形 p 值：η_ood(x) = (1 + #{i: s_i ≥ s(x)}) / (|R|+1)。它给出有限样本、无分布假设的覆盖保证——但只在可交换性下成立，这恰好是本轮最大的诚实边界（见风险）。

**关键洞见**：第 7 轮问「用户想要什么」；第 8 轮问「**凭我们所见过的一切，我们是否有认识论上的资格去行动**」。七硬门记号原样复用；本轮新增：
- IP-505 MAC（记忆锚定保形 OOD 检测器），
- IP-506 LMC-v2（带来源与遗忘的长期记忆整合器），
- IP-507 CBG（案例基泛化器，插值区提议），
- IP-508 EFA-v8（三区制分派；OOD fail-closed 折叠进既有新颖性硬门，不新增硬门）

**形式化目标（增量）**：

1. **MAC（Memory-Anchored Conformal OOD Detector）**：
   - 参考锚集 R_t ⊆ M_t，联合嵌入 φ(x) = [φ_L(L), φ_g(o,g), φ_topo(t_topo), φ_emo(ŝ_emo)]
   - 锚非一致性分数 s_i = 到 R_t\{c_i} 的第 k 近邻距离
   - 查询分数 s(x) = 到 R_t 的第 k 近邻距离
   - 保形支撑度 η_ood(x) = (1 + Σ_{i∈R_t} 1[s_i ≥ s(x)]) / (|R_t| + 1) ∈ (0,1]
   - 阈值：η_ood ≥ 1-α_in → 内分布；α_ood ≤ η_ood < 1-α_in → 插值；η_ood < α_ood → 外推

2. **LMC-v2（Long-term Memory Consolidation v2）**：
   - 案例 c_i = (φ_i, a_i, y_i, e_i, π_i, w_i)，π_i 为来源哈希/签名，w_i 为可信权重
   - 整合算子：w_i ← clip(ρ·w_i + μ·1[y_i=verified] − ν·1[y_i=failed], 0, 1)，ρ 为遗忘衰减
   - 锚集 A_t = {c_i : w_i ≥ w_anchor ∧ y_i=verified ∧ e_i 可验}；案例库容量 |M_t| ≤ N_max，按 w 淘汰
   - 漂移统计 D_t = W₁(P̂_t, P̂_{t-Δ})，超过 τ_drift 触发重标定与锚集重建

3. **CBG（Case-Based Generalizer，仅插值区）**：
   - 检索 A(x) = Top-k_A(φ(x), K=4)
   - 认证邻域：N_ε(a) = {x : ||φ(x)-φ(c_a)|| ≤ ε_a}，ε_a = m_a / L_gate（m_a 为锚的硬门余量，L_gate 为门函数 Lipschitz 常数）
   - 条件化提议：x_gen = FMPP.propose(c ⊕ {φ(c_a), a_a}_{a∈A(x)}, K=8)
   - 约束：仅接受 x_gen 落在任一 N_ε(a) 内且通过七硬门的候选

4. **EFA-v8（三区制分派）**：
   - ECS_v8 = ECS_v7 · η_ood（η_ood 只用于排序/过滤，不降低任何硬门阈值）
   - 内分布：执行 EFA-v7 全流程
   - 插值：CBG 生成候选 + 七硬门 + 认证邻域约束
   - 外推：跳过 FMPP，只允许保守脚手架或 handover；OOD 判定复用既有新颖性硬门，不新增门

5. **形式化定义**：给定查询 x、案例库 M_t、参考锚集 R_t：
   - η_ood(x) = 保形支撑度；s(x), s_i 如上；
   - 若 η_ood ≥ 1-α_in：执行 EFA-v7(x)；
   - 若 α_ood ≤ η_ood < 1-α_in：x_gen = CBG(x, A_t)，若 ∃a: x_gen ∈ N_ε(a) ∧ 七硬门(x_gen) 则执行，否则降级为外推；
   - 若 η_ood < α_ood：x_safe = Scaffold(x) 或 handover，且不进入 FMPP；
   - 记忆更新：M_{t+1} = LMC-v2(M_t, (x, x_exec, y, e))。

**本轮最大风险**：**「记忆锚定的一致性假设在非平稳分布下失效」**：保形支撑度的覆盖保证依赖参考锚与测试流可交换，而长期记忆本身在漂移、整合、淘汰中不断改变分布——一旦可交换性被破坏，η_ood 可能系统性高估陌生情境的支撑度（把危险外推误判为插值），也可能过度保守（把无害新情境判为外推），且整合过程可能把错误「洗白」成锚，使系统在 fail-closed 边界内仍然做出「有证书但证书本身已失效」的行动。

## 2. 关键算法骨架

### IP-505 MAC：记忆锚定保形 OOD 检测器

```python
@dataclass
class MemoryAnchoredConformalOOD:
    """MAC：以长期记忆为参考集，用 k-NN 非一致性分数做保形 OOD 检测。
    无分布假设的有限样本覆盖；仅在可交换性下有效（见诚实声明）。"""
    phi: nn.Module                 # 联合嵌入 φ(x)
    k: int = 8                     # 近邻数
    alpha_in: float = 0.10         # 内分布容忍
    alpha_ood: float = 0.05        # 外推硬边界
    ref_feats: torch.Tensor | None = None
    ref_scores: torch.Tensor | None = None

    def calibrate(self, anchors: list[Case]) -> None:
        """以当前锚集重建参考集与非一致性分数 s_i"""
        feats = torch.stack([self.phi(c.context) for c in anchors])
        self.ref_feats = feats
        self.ref_scores = self._knn_scores(feats, feats,
                                           exclude_self=True, k=self.k)

    def _knn_scores(self, Q, R, exclude_self: bool, k: int) -> torch.Tensor:
        d = torch.cdist(Q, R)                       # O(|Q||R|d)
        if exclude_self:
            d.fill_diagonal_(float('inf'))
        kth = d.topk(k, largest=False).values[:, -1]
        return kth

    def support(self, x) -> tuple[float, str]:
        """返回保形支撑度 η_ood 与区制标签"""
        if self.ref_feats is None or len(self.ref_scores) == 0:
            return 0.0, 'EXTRAPOLATION'             # 冷启动 fail-closed
        s_x = self._knn_scores(self.phi(x)[None], self.ref_feats,
                               exclude_self=False, k=self.k)[0]
        p = (1.0 + (self.ref_scores >= s_x).sum().item()) / (len(self.ref_scores) + 1)
        return p, self._regime(p)

    def _regime(self, p: float) -> str:
        if p >= 1.0 - self.alpha_in:
            return 'IN_DISTRIBUTION'
        if p >= self.alpha_ood:
            return 'INTERPOLATION'
        return 'EXTRAPOLATION'
```

### IP-506 LMC-v2：带来源与遗忘的长期记忆整合器

```python
@dataclass
class LongTermMemoryConsolidationV2:
    """LMC-v2：案例库 + 验证强化 + 遗忘衰减 + 容量淘汰 + 漂移检测。
    每条案例保留来源哈希，保证 OOD 判定可追溯、可审计。"""
    rho: float = 0.995
    mu: float = 0.30
    nu: float = 0.50
    w_anchor: float = 0.70
    w_min: float = 0.05
    n_max: int = 10000
    tau_drift: float = 0.15
    cases: dict[str, Case] = field(default_factory=dict)

    def update(self, x, a_exec, y, evidence, provenance) -> None:
        key = provenance.hash(x)
        if key in self.cases:
            c = self.cases[key]
            c.w = min(1.0, max(0.0,
                self.rho * c.w
                + self.mu * float(y == 'verified')
                - self.nu * float(y == 'failed')))
            c.y, c.e, c.pi = y, evidence, provenance
        else:
            self.cases[key] = Case(x, a_exec, y, evidence, provenance, w=0.5)
        self._evict()

    def _evict(self) -> None:
        for k in [k for k, c in self.cases.items() if c.w < self.w_min]:
            del self.cases[k]
        if len(self.cases) > self.n_max:
            keep = sorted(self.cases.items(),
                          key=lambda kv: kv[1].w, reverse=True)[:self.n_max]
            self.cases = dict(keep)

    def anchors(self) -> list[Case]:
        return [c for c in self.cases.values()
                if c.w >= self.w_anchor
                and c.y == 'verified'
                and c.e.verifiable]

    def drift(self, prev_stats, cur_stats) -> float:
        """记忆分布漂移；超 τ_drift 触发 MAC 重标定与锚集重建"""
        return sinkhorn_w1(prev_stats, cur_stats)
```

### IP-507 CBG：案例基泛化器（仅插值区）

```python
@dataclass
class CaseBasedGeneralizer:
    """CBG：把已认证锚作为流匹配条件，在认证邻域内生成轨迹。
    认证邻域由硬门余量与 Lipschitz 常数导出，保证局部证书迁移。"""
    fmpp: FlowMatchingProposalPolicyKernel
    phi: nn.Module
    l_gate: float = 2.0            # 硬门 Lipschitz 常数（离线标定）
    k_anchor: int = 4

    def certified_radius(self, anchor: Case) -> float:
        m = anchor.e.min_margin    # 锚在七硬门上的最小余量
        return max(0.0, m / self.l_gate)

    def propose(self, x, anchors: list[Case], K: int = 8):
        cond = build_anchor_conditioning(x, anchors)
        cands = self.fmpp.propose(cond, K=K)
        out = []
        for xg in cands:
            for a in anchors:
                if torch.norm(self.phi(xg) - self.phi(a.context)) \
                        <= self.certified_radius(a):
                    out.append((xg, a))
                    break
        return out
```

### IP-508 EFA-v8：三区制分派

```python
@dataclass
class EvidenceForgingAssemblerV8:
    """EFA-v8：内分布→v7；插值→CBG；外推→保守脚手架/求助。
    OOD fail-closed 折叠进既有新颖性硬门，硬门数不增。"""
    v7: EvidenceForgingAssemblerV7
    mac: MemoryAnchoredConformalOOD
    lmc: LongTermMemoryConsolidationV2
    cbg: CaseBasedGeneralizer
    scaffold: ConservativeScaffoldPolicy
    drift_window: int = 200

    def select(self, x, t_now):
        eta_ood, regime = self.mac.support(x)

        # 1. 内分布：原 v7 流程
        if regime == 'IN_DISTRIBUTION':
            ok, traj, tag = self.v7.select(x.L, t_now, x.context)
            self._commit(x, traj, tag)
            return ok, traj, f'{tag}|OOD_IN'

        # 2. 插值：案例基泛化 + 七硬门 + 认证邻域
        if regime == 'INTERPOLATION':
            anchors = self._nearest_anchors(x, K=self.cbg.k_anchor)
            cands = self.cbg.propose(x, anchors, K=8)
            certified = [(xg, a) for xg, a in cands
                         if self.v7.hard_gates_pass(xg, x.context, t_now)]
            if certified:
                xg, a = max(certified, key=lambda p: self._margin(p[0]))
                self._commit(x, xg, 'CBG')
                return True, xg, f'CBG_INTERP|anchor={a.pi.hash}'
            regime = 'EXTRAPOLATION'      # 插值失败 → 降级外推

        # 3. 外推：fail-closed，不进入 FMPP
        x_safe = self.scaffold.plan(x)
        self._commit(x, x_safe, 'SCAFFOLD')
        return (x_safe is not None), x_safe, 'OOD_EXTRAPOLATION_FAILCLOSED'

    def _nearest_anchors(self, x, K: int) -> list[Case]:
        A = self.lmc.anchors()
        if not A:
            return []
        feats = torch.stack([self.mac.phi(a.context) for a in A])
        d = torch.norm(feats - self.mac.phi(x)[None], dim=1)
        idx = d.topk(min(K, len(A)), largest=False).indices
        return [A[i] for i in idx.tolist()]

    def _commit(self, x, traj, tag) -> None:
        if traj is None:
            return
        y = 'verified' if self._postcheck(traj) else 'failed'
        self.lmc.update(x, traj, y, self._evidence(traj), Provenance(tag))
        if self._drift_due():
            self.mac.calibrate(self.lmc.anchors())
```

### 集成流水线（v7 → v8）

```
离线/慢时域：
  MAC 标定（分钟级）：从 LMC-v2 锚集重建 R_t 与 s_i 分布
  L_gate 标定（小时级）：离线扰动 φ 空间，估计七硬门分数 Lipschitz 常数
  CBG 条件编码器训练（小时级）：以锚-动作对为条件样本
  联邦下发：φ 权重、L_gate、α_in/α_ood、τ_drift → 站内签名分发

在线准入（亚秒级）：
  φ(x) ──▶ MAC.support(x) ──▶ η_ood, regime
  若 regime=IN      : EFA-v7 全流程（软因子链不变）
  若 regime=INTERP  : A(x)=Top-k 锚 → CBG.propose → 七硬门 + N_ε 约束
  若 regime=EXTRAP  : Scaffold(x) 或 handover；不进入 FMPP

在线控制环（目标 < 0.9 ms）：
  MAC 支持度：ANN 近似 k-NN，O(log|R|)，约 0.1~0.2 ms
  CBG：仅插值区触发，锚数 k=4，额外 0.2~0.4 ms
  外推区：零 FMPP 开销，最坏时延反而下降
```

## 4. 正确性论证（增量更新）

### 定理 13（保形 OOD 的误报控制）

**陈述**：设参考锚集 R_t 与内分布测试流满足可交换性，非一致性分数连续无并列。则对任意 α_in ∈ (0,1)：
- P(η_ood(x) < α_in | x ~ P_in) ≤ α_in

即内分布输入被误判为「非内分布」的比例受 α_in 控制。

**证明**：保形 p 值 η_ood(x) 在可交换性下服从离散均匀分布（秩的对称性）；P(p < α) ≤ α 为保形预测的标准覆盖结论。对 k-NN 非一致性分数只需分数可交换，与数据分布无关。

**注意**：该定理只控制「内分布被误判为 OOD」（type I，误报），**不控制**「OOD 被误判为内分布」（type II，漏报）——后者无分布假设下不可界，正是本轮最大风险的来源。

### 定理 14（局部证书迁移）

**陈述**：设七硬门分数函数 g(·) 在 φ 空间 L_gate-Lipschitz，锚 a 的余量 m_a = g(a) - τ > 0。若查询 x 与锚满足 ‖φ(x)-φ(c_a)‖ ≤ m_a / L_gate，则把锚动作 a 迁移到 x 上仍通过同一硬门。

**证明**：|g(x) - g(a)| ≤ L_gate·‖φ(x)-φ(c_a)‖ ≤ m_a，故 g(x) ≥ g(a) - m_a = τ，门判定保持通过。

**推论**：CBG 只在 N_ε(a) 内接受候选，则插值区执行集 ⊆ 已验证锚的认证邻域之并，每个邻域内硬门结果由连续性保证。

### 定理 15（fail-closed 保持与执行集包含）

**陈述**：设 v8 的七硬门判定与 v7 相同，且外推区不调用 FMPP。则：
- Exec_v8^extrap ⊆ Exec_v7^safe（外推区只执行保守脚手架/handover）
- Exec_v8^interp ⊆ ⋃_{a∈A_t} N_ε(a) ∩ Exec_v7
- 整体 Exec_v8 ⊆ Exec_v7 ∪ {Scaffold(x)}，不扩张已验证执行集

**证明**：外推区按定义跳过 FMPP，只输出 Scaffold；插值区每个候选必须落在某锚的认证邻域并通过七硬门，由定理 14 证书可迁移；内分布区直接调用 v7。三区之并即得结论。

### 诚实声明

- **可交换性是硬前提**：定理 13 的覆盖保证依赖 R_t 与测试流可交换；长期记忆的漂移、整合、淘汰会破坏它，此时 η_ood 的标定可能失效，需靠 D_t 漂移检测触发重标定，但重标定本身也有滞后。
- **保形不控制漏报**：定理 13 只保证误报有界；「危险 OOD 被判为内分布」无分布假设下不可界，因此仍需七硬门的物理/几何兜底，而不是把安全完全托付给 η_ood。
- **记忆洗白**：LMC-v2 的强化规则可能把「碰巧通过一次硬门」的失败案例误标为 verified，逐步污染锚集；来源哈希与人工抽检只能缓解，无法根除。
- **锚集稀疏**：外推区判定对 |R_t| 与 k 敏感；冷启动期锚集为空，系统几乎全部 fail-closed，这是安全的，但可用性极低。
- **认证邻域保守性**：L_gate 估计偏大则 ε 偏小，插值区退化为外推区（过度保守）；偏小则证书迁移失效（不安全）。L_gate 的离线标定质量直接决定 CBG 的可用边界。

## 7. 本轮最大风险（最终确认）

**一句话**：**「记忆锚定的一致性假设在非平稳分布下失效」**：保形支撑度的覆盖保证依赖参考锚与测试流可交换，而长期记忆本身在漂移、整合、淘汰中不断改变分布——一旦可交换性被破坏，η_ood 可能系统性高估陌生情境的支撑度（把危险外推误判为插值），也可能过度保守（把无害新情境判为外推），且整合过程可能把错误「洗白」成锚，使系统在 fail-closed 边界内仍然做出「有证书但证书本身已失效」的行动。
