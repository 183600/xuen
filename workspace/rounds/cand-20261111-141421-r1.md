# 第 55 轮（承接第 54 轮 v31 GroundEdge-GenSim+++；灵感循环第 6 轮；本轮灵感：「手势识别」×「用户需求分析」）

> 第 54 轮把技能组合推进为“动作空间剖面 + 动作-鲁棒性联合证书”，但所有证书都默认 **任务 T 已被正确给定**。本轮把视角上移到 **任务规格的上游**：手势是低带宽、高歧义的意图通道，用户需求是可能被误述且会漂移的目标来源。核心矛盾：H22：手势→任务是一对多映射，识别置信度不能等同于用户意图，下游动作证书再完备也纠不回上游误读；H23：用户“真实需求”与“可表述需求”之间存在鸿沟且随时间漂移，系统可能精确地优化了错误的目标。

## 0. 直觉与动机

**灵感 1（手势识别 → 输出“意图信念”而非硬标签）**
直觉：一个手势 g 并不唯一决定任务 T。同一“挥手”可能是打招呼、拒绝、驱赶或请求跟随，取决于上下文 c 与用户习惯。因此识别器的正确输出不是一个 `argmax` 标签，而是任务空间上的后验 `β_g(T)=P(T|g,c,ℳ)` 与歧义熵 `H_g`。当 `H_g` 高或最大后验不显著时，系统不应“猜着执行”，而应进入澄清态。**把识别的输出从 point estimate 改成 belief，是从根上承认意图不可观测。**

**灵感 2（动作接地手势语义 → 识别被“可执行性”反向约束）**
直觉：第 54 轮是“规划 → 动作空间”，本轮增加反向箭头：**动作空间 → 识别**。一个手势解释只有在所需动作序列 `A_T=τ(req(T))` 能被技能库某条组合覆盖时，才是“可执行接地”的。于是定义可接地解释集 `Γ(g,c)={T∈supp(β_g) | A_T ⊆ cover(𝒫)}`，并把落不进 `Γ` 的概率质量视为 **语义悬空（semantic suspension）**。这把识别从纯感知问题变成“感知-动作联合推断”，也让“听不懂/做不到”成为可报告的一等状态，而不是静默失败。

**灵感 3（用户需求分析 → 需求-动作可追溯与覆盖缺口）**
直觉：用户“需求”N 与“表述需求”N_s 不是一回事，潜在需求 N_l 常靠观察纠错行为才暴露。把需求经 `req(·)` 映射到任务、再经 `τ(·)` 映射到动作需求，构建 **需求-动作追溯图**，并在其上计算 **需求-动作覆盖 `cov(N,𝒫)`**。未覆盖的 `N_gap` 不是 bug，而是 **能力缺口的产品信号** —— 它告诉研究该补哪个技能，而不是继续在已覆盖需求上刷指标。这把第 54 轮的动作覆盖从“任务内”提升到“需求族”层面。

**灵感 4（主动澄清 → 把“问用户”当成一个动作来规划）**
直觉：澄清不是失败，而是一个有信息收益、也有交互成本的动作。重做手势、二选一确认、展示候选技能，都是 `q∈Q`。用期望信息增益 `IG(q)` 与成本 `c(q)` 的比值决定是否澄清、澄清什么。**能问则问，问要有性价比；宁可多问一句，也不要在高歧义下自信地做错事。** 这把第 54 轮的云-边 Explain 闭环扩展为“云-边-人”三环。

**灵感 5（需求漂移 → 需求级 Explain 与再认证）**
直觉：用户需求会漂移（新场景、新习惯、新手势词汇），已部署证书会 **静默过期**。把漂移检测放在手势分布与需求分布上，一旦漂移触发，就沿追溯图定位受影响证书并重跑 SCOM/CEC/AEC。这把 Explain 从“执行失败根因”扩展到 **“目标本身变了”的根因**，形成需求级再认证闭环。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（手势意图信念）**
手势观测 `g∈G`（时序骨架/轨迹），上下文 `c∈C`（用户、场景、任务历史）。意图信念 `β_g∈Δ(𝒯)`，`β_g(T)=P(T|g,c,ℳ)`。歧义熵 `H_g=-Σ_T β_g(T)log β_g(T)`。**歧义态判据**：`H_g>θ_H ∨ max_T β_g(T)<θ_conf`。

**定义 122（动作接地手势语义）**
设技能库可生成的组合集合为 `𝒫`，任务 T 的所需动作 `A_T=τ(req(T))`。**可接地解释集** `Γ(g,c)={T∈supp(β_g) | ∃P∈𝒫, A_T⊆cover(P)}`。语义悬空率 `sus(g)=1-Σ_{T∈Γ}β_g(T)`。若 `Γ=∅`，手势 **不可接地**，必须澄清或拒答。

**定义 123（需求空间与需求-动作追溯）**
需求空间 `N`，表述需求 `N_s⊆N`，潜在需求 `N_l=N\N_s`。`req:N→ℛ`，`τ:ℛ→2^{𝒜_T}`。追溯映射 `tr:N→2^{𝒫}`，`tr(n)={P∈𝒫 | A_T(n)⊆cover(P)}`。**需求鸿沟** `Gap_req=N_l`。

**定义 124（需求-动作覆盖）**
`cov(N,𝒫)=|{n∈N | tr(n)≠∅}|/|N|`；缺口集 `N_gap={n∈N | tr(n)=∅}`。第 54 轮 `cover(S,A_T)` 是其在单需求单任务上的特例。

**定义 125（澄清动作与信息增益）**
澄清动作 `q∈Q`，观测 `o`。`IG(q)=H_g - E_{o∼q}[H(β_g|o)]`，成本 `c(q)`（含打断成本与延迟）。策略 `q*=argmax_q IG(q)/c(q)`，仅当 `H_g>θ_H` 且 `IG(q*)/c(q*)≥θ_ig` 时发起；否则 **保守拒答并给候选**。

**定义 126（手势-需求-动作联合证书 NGA）**
`NGA=(β_g,H_g,Γ,tr,cov,A_cert,ρ,γ_ce,δ_ground,evidence)`，其中 `δ_ground` 为接地漂移（手势语义与需求分布在时间窗上的位移）。**部署判据**：
```
H_g≤θ_H ∧ sus(g)≤Θ_s ∧ cov(N_req,𝒫)≥θ_cov
∧ δ_ground≤Θ_g ∧ ρ≥ρ_min ∧ δ_a≤Θ_a
```
任一项不满足则返回 `clarify / reject_need_gap / reject_grounding`，不得进入执行。

## 2. 关键算法 伪代码

### IP-121 GIB（Gesture Intent Belief）

```python
def gesture_belief(g, c, model, T_space):
    logits = model.score(g, c, T_space)          # 多任务打分
    beta = softmax(logits)
    H = -sum(p*log(p) for p in beta.values() if p > 0)
    return beta, H

def ambiguity_gate(beta, H, theta_H=0.6, theta_conf=0.7):
    return H > theta_H or max(beta.values()) < theta_conf
```

### IP-122 NGC（Need Grounding Certificate）

```python
def need_grounding_certificate(g, c, needs, trace, gamma_ce, J_budget):
    beta, H = gesture_belief(g, c, model, tasks)
    Gamma = {T for T in beta if trace.has_feasible(req(T))}   # 动作接地约束
    sus = 1 - sum(beta[T] for T in Gamma)
    if ambiguity_gate(beta, H) or sus > THETA_S:
        q = active_clarify(beta, H, Q, cost)
        return ('clarify', q, beta, H, sus)        # 不猜、不静默执行
    if not Gamma:
        return ('reject', 'ungroundable')
    T = max(Gamma, key=lambda t: beta[t])
    cov, gap = need_coverage(trace)
    if cov < THETA_COV:
        return ('reject', 'need_gap', gap)          # 能力缺口，不是执行失败
    P = select_composition(trace, T)
    J = joint_certificate(P, gamma_ce, J_budget.delta_a, J_budget.rho_min)  # 第54轮 AEC
    if J.status != 'ok':
        return ('reject', 'action_robust_fail', J)
    return ('ok', NGA(beta, H, Gamma, trace, cov, J.A_cert, J.rho,
                      gamma_ce, delta_ground=estimate_drift(g, c)))
```

### IP-123 NAT（Need-Action Traceability）

```python
def build_traceability(needs, skill_lib, req, tau, cover_check):
    G = TraceGraph()
    for n in needs:
        A_T = tau(req(n))
        feasible = [P for P in compositions(skill_lib) if cover_check(P, A_T)]
        G.add(n, req(n), A_T, feasible)
    return G

def need_coverage(trace):
    covered = {n for n in trace.needs if trace.feasible(n)}
    return len(covered)/len(trace.needs), trace.needs - covered
```

### IP-124 ACQ（Active Clarification Query）

```python
def active_clarify(beta, H, Q, cost, theta_ig=0.2, EPS=1e-9):
    if H <= theta_H:
        return None
    best, best_ratio = None, 0.0
    for q in Q:
        post = expected_posteriors(beta, q)          # 模拟各观测后的后验
        IG = H - sum(pr*entropy(p) for pr, p in post)
        ratio = IG / max(cost[q], EPS)
        if ratio > best_ratio:
            best, best_ratio = q, ratio
    return best if best_ratio >= theta_ig else ('defer', best)
```

### IP-125 GDD（Gesture-Need Drift Detection）

```python
def detect_drift(g_stream, n_stream, W=200, alpha=0.01):
    dg = distribution_shift(g_stream[-W:], g_stream[-2*W:-W])   # MMD/KS
    dn = distribution_shift(n_stream[-W:], n_stream[-2*W:-W])
    return DriftReport(g=dg, n=dn, trigger=(dg > tau_g or dn > tau_n))
```

### IP-126 RRC（Requirement Re-Certification）

```python
def recertify_after_drift(trace, drift, certs):
    affected = {c for c in certs if drift.touches(c.need)}   # 沿追溯图反向定位
    for c in affected:
        c.status = 'stale'
        new_trace = build_traceability(c.need, skill_lib, req, tau, cover_check)
        if need_coverage(new_trace)[0] < THETA_COV:
            escalate_to_need_gap(new_trace)                  # 需求级 Explain
            continue
        rebuild_and_recertify(c, new_trace)                  # SCOM→CEC→AEC
    return affected
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| GIB | O(\|G\|·\|𝒯\|·d) | O(\|𝒯\|) | 概率校准 ECE 有界 |
| NAT | O(\|N\|·\|𝒫\|·\|A\|) | O(\|N\|+\|𝒫\|) | req/τ 映射 sound |
| ACQ | O(\|Q\|·\|𝒯\|·s) | O(\|Q\|·\|𝒯\|) | IG 估计无偏、成本可测 |
| NGC | O(\|𝒯\|·\|𝒫\|·\|A\|) | O(\|𝒫\|+\|A\|) | 接地集裁剪 sound |
| GDD | O(W·\|G\|) | O(W) | 漂移误报受控 |
| RRC | O(\|affected\|·(\|S\|²·\|A\|)) | O(\|S\|²) | 追溯定位完备 |

**正确性定理（Need-Grounded Deployment Soundness, NGDS）**
承接第 54 轮 (A26)–(A28)；新增 **(A29)** `β_g` 已校准，`ECE≤ε_cal`；**(A30)** `req/τ` 在采样需求上 sound，追溯不遗漏可行组合；**(A31)** 漂移检测漏报率 `≤β_d`。
则对任一需求 `n`：
```
P(success | n) ≥ 1 - ε_cal - (1-cov(N,𝒫)) - P(sus(g)>Θ_s) - P(δ_ground>Θ_g) - Σ_d(1-ρ_min(d)) - β_d
```
关键：**意图先校准、需求先覆盖、接地先可执行、漂移先重认证**；四项任一不满足，宁可澄清也不执行。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 手势信念过自信（校准差） | 高 | 温度标定 + 一致性正则 + 拒识阈值 |
| 需求挖掘偏差（表述≠真实） | 高 | 行为弱标签（重复/纠错手势）+ 用户访谈三角验证 |
| 澄清过频导致用户疲劳 | 中 | 信息增益/成本门控 + 会话预算 + 习惯缓存 |
| 漂移检测震荡 | 中 | 双窗 + 迟滞 + 人工确认锚点 |
| 跨文化/个体手势语义差异 | 高 | 个性化手势词典 + 共享本体 + 在线适配 |

## 6. 本轮最大风险

**一句话**：本轮把证书链从“动作-鲁棒性”上延到“手势-需求-动作”，但新增的两段都是 **不可观测且有偏的上游**——手势信念若过自信、需求若被误述，下游再完备的动作与鲁棒性证书也只是把一个错误目标证得更漂亮；因此必须以 **概率校准 + 行为弱标签/三角验证 + 澄清优先于执行 + 语义负债绊线** 四重护栏，宁可多问一句、宁可拒答，也绝不把“意图接地的假象”当作可部署前提。

# 第 55 轮产物 · 创新点清单 v32：GroundEdge-Intent（GIB×NAT×ACQ×NGC×GDD×RRC）

> 承接第 54 轮产物 v31（GroundEdge-GenSim+++）。第 54 轮解决了“给定任务 T 后，技能组合能否在动作空间与鲁棒性上安全部署”；本轮解决 **“T 本身从哪来、是否被正确理解、是否会过期”**。为此新增 **意图接地（Intent Grounding）** 层：
> - **GIB（Gesture Intent Belief）**：手势识别输出意图信念 `β_g` 与歧义熵 `H_g`，不直接输出硬标签；
> - **NAT（Need-Action Traceability）**：需求→表达→任务→动作的追溯图，计算需求-动作覆盖与缺口；
> - **ACQ（Active Clarification Query）**：以期望信息增益/成本决定“问不问、问什么”；
> - **NGC（Need Grounding Certificate）**：手势-需求-动作联合证书，把“可执行接地”作为部署前提；
> - **GDD（Gesture-Need Drift Detection）**：手势与需求分布的漂移检测；
> - **RRC（Requirement Re-Certification）**：漂移触发需求级 Explain 与再认证。
>
> IP 编号：IP-121~IP-126（共 6 个新增），升级 IP-115/117/118/120，使其证书携带意图与需求溯源。

```python
    for c in affected:
        c.status = 'stale'
        new_trace = build_traceability(c.need, skill_lib, req, tau, cover_check)
        if need_coverage(new_trace)[0] < THETA_COV:
            escalate_to_need_gap(new_trace)       # 需求级 Explain：目标变了
            continue
        rebuild_and_recertify(c, new_trace)       # SCOM → CEC → AEC
    return affected
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| GIB | O(\|G\|·\|𝒯\|·d) | O(\|𝒯\|) | 概率校准 ECE ≤ ε_cal |
| NAT | O(\|N\|·\|𝒫\|·\|A\|) | O(\|N\|+\|𝒫\|) | req/τ sound，追溯完备 |
| ACQ | O(\|Q\|·\|𝒯\|·s) | O(\|Q\|·\|𝒯\|) | IG 估计无偏，成本可测 |
| NGC | O(\|𝒯\|·\|𝒫\|·\|A\|+\|𝔇_ρ\|) | O(\|𝒫\|+\|A\|) | 接地集裁剪 sound，判据闭合 |
| GDD | O(W·\|G\|) | O(W) | 漏报 ≤ β_d，误报受控 |
| RRC | O(\|affected\|·\|S\|²·\|A\|) | O(\|S\|²) | 追溯定位完备，无静默过期 |

**正确性定理（Need-Grounded Deployment Soundness, NGDS）**
承接第 54 轮 (A26)–(A28)；新增 **(A29)** `β_g` 已校准 `ECE≤ε_cal`；**(A30)** `req/τ` 在采样需求上 sound；**(A31)** 漂移漏报率 `≤β_d`。则对任一需求 `n`：
```
P_success(n) ≥ 1 - ε_cal - (1-cov(N,𝒫)) - P(sus(g)>Θ_s) - P(δ_ground>Θ_g)
                - Σ_d(1-ρ_min(d)) - β_d
```
关键：**先校准意图、再验证覆盖、再确认接地、最后才做动作-鲁棒性证书**；四项任一不满足即澄清或拒答。

## 5. 本轮最大风险

**一句话**：本轮把证书链从“动作-鲁棒性”上延到“手势-需求-动作”，但新增的两段都是 **不可观测且有偏的上游**——手势信念若过自信、需求若被误述，下游再完备的动作与鲁棒性证书也只是把一个错误目标证得更漂亮；因此必须以 **概率校准 + 行为弱标签/三角验证 + 澄清优先于执行 + 语义负债绊线** 四重护栏，宁可多问一句、宁可拒答，也绝不把“意图接地的假象”当作可部署前提。
