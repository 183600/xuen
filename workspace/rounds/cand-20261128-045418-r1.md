### 第 6 轮灵感驱动研究记录

**灵感词**：续航能力、多视角视觉

**继承关系**：第 5 轮 CADVS-v5（IP-493~496）把提议器升级为条件流匹配、记忆升级为嵌入+固化、人因升级为情感调制，并以定理 6（证书不变性/提议无关性）确立「提议可换、门不可换」。v5 有三个未言明的前提：认证（VACK/BCK/流似然/FER）在能量与时间上免费、证书永久有效、感知是单视角的。本轮两个灵感词正好击穿这三点：续航能力 → 认证是消耗能量的稀缺资源、证书会随状态漂移过期；多视角视觉 → 单视角有遮挡与深度歧义，而多视角若乐观融合会幻觉出自由空间。统一主题「认证的可持续执行」（Certified Sustainable Execution, CSE），形成 CADVS-v6（IP-497~500）。本轮自律不变：**硬门数量仍为七**（不再靠新增门回应 R52），只加**两个单调收缩算子**（能量预算算子 Π_E、证书时效算子 Π_τ）与**一个保守感知精化**（多视角仅收紧 κ_mv），执行集嵌套升级为 Exec_CADVS-v6 ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29。

**直觉与动机**：

1. **续航能力 → 认证经济学：能量是认证的预算，不是门的替代品**。
   - **直觉**：机器人要跑 8 小时，不可能每 0.1 秒做一次 BCK 全量 QP；电量低时最危险的做法恰恰是「跳过检查以省电」。正确做法是把能量显式建模为认证的预算约束：预算越少，**能被认证的候选越少**，执行集单调收缩，最终退回到离线预认证的「安全内核」（保持位姿 / 柔顺回撤），而不是在无认证下继续动作。这把 v5 的「实时性缓解」从工程技巧提升为**资源约束下的安全定理**：能量只决定「能认证多少」，永不决定「是否绕过门」。
   - **严谨定义**：认证动作 a 有能量代价 c(a)=Σ_{i∈a} c_i 与时间 τ(a)；完整证书必须过全部七门。定义带预算的执行集 Exec_v6(E) = S_0 ∪ {x : 存在总代价 ≤ E 的完整认证计划}，其中 S_0 ⊆ Exec_v5 是离线预认证、零在线认证代价、在状态域 D_0 上恒有效的安全内核。于是 E1 ≤ E2 ⇒ Exec_v6(E1) ⊆ Exec_v6(E2) ⊆ Exec_v5，且 Exec_v6(0)=S_0≠∅。调度上用「证书背包」：按 certified_margin/cost 密度排序，取「密度贪心」与「单件最优」的较大者，得 1/2 近似。另设能量感知提议：能耗作为软因子 η_energy 进入排序与流条件，让候选天生更省电，但**不改门**。
   - **证书时效**：证书 cert=(x, t_mint, s_ref, ρ, T_fresh)；有效谓词 fresh(cert; s,t)=1[d_G(s,s_ref)≤ρ]·1[t−t_mint≤T_fresh]。漂移或超龄即删除——证书不是永久真值，而是带 TTL 的租约，「再认证」必须计入续航预算。

2. **多视角视觉 → 保守融合：多视角只用来「看见更多危险」，不用来「宣布更多自由」**。
   - **直觉**：单视角被遮挡的区域，乐观算法会当成自由空间，这是碰撞的根源；多视角的价值是冗余与几何一致性，但若直接取并集（任一视角说自由就自由）会幻觉。因此采用**保守多视角融合**：一个体素只有被 ≥ V_min 个视角一致确认为自由才算自由，否则（遮挡/未知/不一致）一律按占据处理（fail-closed）。
   - **严谨定义**：F=fuse({D_v,T_v})，free(voxel) ⇔ n_vox ≥ V_min ∧ r_vox ≤ δ_mv ∧ 符号一致；未知/遮挡 = 占据。定义视角不一致度 D_mv（轨迹扫掠体素中残差超阈比例）与遮挡率 o_mv，驱动**非对称阈值调制** γ_mv,i = 1 + κ_i^mv·clip(o_mv + 1[D_mv>δ_mv],0,1) ≥ 1，只在多视角互相矛盾/遮挡严重时收紧覆盖与物理门。多视角的吞吐收益走另一条路：更准的几何嵌入 g_emb^mv 与占据上下文进入流提议——**提议变好、边界不动**（复用定理 6）。因此多视角不可能放宽任何门，只会收紧或不变。

**关键洞见**：v5 回答「提议任意、记忆反哺、情感调制时，证书边界如何不变」；v6 回答「**当认证本身有能量代价、证书会过期、感知有遮挡歧义时，如何让边界只缩不涨、并在电量耗尽前优雅退化**」。七硬门 kc_evidence_forged_v5 原样复用；v6 新增的只有：能量预算算子 Π_E、证书时效算子 Π_τ、多视角保守精化 κ_mv（仅收紧）、软评分 ECS_v6 = ECS_v5 · η_energy · η_mv。执行集嵌套由「同门 + 只加合取条件 + 只紧调制」三重保证。

**形式化目标（增量）**：
1. 认证经济学：能量预算 E(t)、认证动作 a、代价 c(a)、时间 τ(a)；证书背包按 margin/cost 贪心；安全内核 S_0 离线预认证。
2. 证书时效：cert=(x, t_mint, s_ref, ρ, T_fresh)；fresh 谓词；漂移/超龄即删除（定理 10）。
3. 多视角保守融合：free ⇔ 多视角一致确认；未知/遮挡=占据；D_mv、o_mv；γ_mv ≥ 1（定理 11）。
4. 能量单调收缩：Exec_v6(E1) ⊆ Exec_v6(E2) ⊆ Exec_v5（E1≤E2）；E→0 退化为非空 S_0（定理 9）。
5. 续航-覆盖可行性：漂移速率 ≤ v_max、单次重认证能耗 c、时域 T 下，连续覆盖可行 ⇔ E ≥ c·T·v_max/ρ；否则覆盖比例 = min(1, E·ρ/(c·T·v_max))（定理 12）。
6. Exec_CADVS-v6 = {x ∈ Exec_v5 : fresh(cert_x) ∧ energy_feasible(x) ∧ kc_mv(x)=1 ∧ ∧_i kc_i(x; γ_i^6 τ_i^5)=1} ⊆ Exec_CADVS-v5，其中 γ_i^6 = 1 + min(Δ_max/τ_i^5, (γ_i^emo−1)+(γ_i^mv−1)) ≥ 1。

**本轮最大风险**：**证书经济学的计量可信性**——整套收缩论证把安全寄托在「电量估计」与「状态漂移检测」这两个新的信任根上；若电池模型系统性高估剩余能量，或漂移检测漏报使过期证书被误判为新鲜，本应收缩的执行集就不会收缩，fail-closed 在资源层退化为 fail-open（系统带着过期证书、在电量将尽时继续动作）；对抗者还可通过耗尽能量实施「安全内核拒绝服务」。

### IP-497 ECBK：认证经济学核（准入/调度时域，不在 1 kHz 环）

```python
@dataclass
class EnergyCertificateBudgetKernel:
    """ECBK：认证经济学。
    定理 9：能量单调收缩；定理 10：时效收缩；定理 12：续航-覆盖可行性。
    红线：能量只决定"能认证多少"，永不决定"是否绕过门"。"""
    e_cap: float
    e_soc: Callable[[], float]          # 剩余能量保守下界（J）
    cost: dict                          # 各门认证能耗 c_i（J）
    reserve: float = 0.08               # 硬保留比例
    rho: float = 0.05                   # 证书漂移半径
    t_fresh: float = 2.0                # 证书年龄上限（s）
    cache: dict = field(default_factory=dict)   # key -> cert

    def below_reserve(self) -> bool:
        return self.e_soc() <= self.reserve * self.e_cap

    def fresh(self, cert, s_now, t_now) -> bool:
        return (drift(s_now, cert.s_ref) <= self.rho
                and t_now - cert.t_mint <= self.t_fresh)

    def plan(self, cands, gates, s_now, t_now) -> list[Plan]:
        """证书背包：完整认证代价 c(x)；按 certified_margin/cost 密度排序。
        分数背包贪心最优；0/1 取 max(密度贪心, 单件最优)，保证 1/2 近似（引理 45）。
        未进入计划的候选不产生证书 → 不进入执行集（fail-closed）。"""
        budget = max(0.0, self.e_soc() - self.reserve * self.e_cap)
        plans = [Plan(x, sum(self.cost[g] for g in gates)) for x in cands]
        plans.sort(key=lambda p: p.value / p.cost, reverse=True)
        return self._best_of_greedy_and_single(plans, budget)

    def mint(self, x, s_now, t_now) -> None:
        self.cache[key(x)] = Cert(x, t_mint=t_now, s_ref=s_now,
                                  rho=self.rho, t_fresh=self.t_fresh)

    def safe_kernel(self, s_now) -> Trajectory:
        """S_0：离线预认证、零在线认证代价；E→0 的非空兜底（定理 9）"""
        return self.s0.lookup(s_now)
```

```python
    刷新策略达到该下界，故充分。∎
    工程含义：续航不是"电池容量"问题，而是"漂移速率 × 重认证成本"问题——降漂移比堆电池更有效。
    """
    return "Proven"
```

### IP-499 EFA-v6：七硬门 + 能量预算 + 时效 + 多视角保守精化

```python
@dataclass
class EvidenceForgingAssemblerV6:
    """EFA-v6：七硬门不变；新增 Π_E、Π_τ、κ_mv（全部只缩不涨）"""
    v5: EvidenceForgingAssemblerV5
    ecbk: EnergyCertificateBudgetKernel
    mvcpk: MultiViewConservativePerceptionKernel

    def select(self, x0_state, t_now, rule_id, context):
        s_now = context.state
        # 1) 能量红线：低于硬保留 → 只允许安全内核（定理 9）
        if self.ecbk.below_reserve():
            return True, self.ecbk.safe_kernel(s_now), 'SAFE_KERNEL_ENERGY'
        # 2) 多视角保守融合 + 仅收紧调制（定理 11）
        occ = self.mvcpk.fuse(context.depths)
        D_mv, o_mv = self.mvcpk.disagreement(context.preview, occ)
        gamma = combine_gamma(self.v5.gamma_emo(context),
                              self.mvcpk.gamma_mv(D_mv, o_mv))   # 逐门 ≥1，有界
        # 3) 证书缓存：新鲜且视角一致则复用，省一次全量认证能耗
        cached = self.ecbk.lookup_fresh(rule_id, s_now, t_now)
        if cached is not None and self._mv_consistent(cached.x, occ):
            return True, cached.x, 'CACHED_FRESH'
        # 4) 提议：多视角几何/占据/能耗进入条件（提议变好，边界不动）
        cands = self.v5.fmpp.propose(build_ctx(context, occ, gamma), self.v5.fmpp.K)
        # 5) 证书背包：只在预算内完整认证（fail-closed）
        plans = self.ecbk.plan(cands, gates=SEVEN_GATES, s_now=s_now, t_now=t_now)
        for plan in plans:
            if not self._mv_gate(plan.x, occ, gamma):        # 一致性/遮挡保守
                continue
            ok, x, tag = self.v5.evaluate_candidate(plan.x, gamma, context)
            if ok:
                self.ecbk.mint(x, s_now, t_now)              # 附 mint 元数据
                return True, x, 'FORGED_CSE'
        return False, None, 'BUDGET_OR_GATE_REJECT'

    def ecs_v6(self, base, e_hat, D_mv, o_mv) -> float:
        eta_energy = exp(-BETA * normalize(e_hat))
        u = clip(o_mv + float(D_mv > DELTA_MV), 0.0, 1.0)
        eta_mv = 1.0 - self.mvcpk.lam_mv * u
        return base * eta_energy * eta_mv
```

## 3. 复杂度分析（增量更新）

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 | 实时性指标 |
|---|---|---|---|---|
| MVCPK.fuse | O(V·N_vox) TSDF | O(N_vox) | V=3~5, N_vox~2e5 | 10–20 ms GPU，异步 |
| MVCPK.disagreement | O(\|swept\|) | O(1) | — | < 1 ms |
| γ_mv / η_mv | O(1) | O(1) | — | < 0.01 ms |
| EC BK.plan | O(K log K) | O(K) | K=8 | < 0.05 ms |
| 证书缓存查询 | O(1) 哈希 + O(d) 漂移 | O(\|cache\|) | \|cache\| ≤ 5k | < 0.1 ms |
| 证书 mint | O(1) | O(1) | — | < 0.01 ms |
| 能量/时效红线 | O(1) | O(1) | — | < 0.01 ms |
| EFA-v6 在线增量 | — | — | — | 异步准入 + 控制环不变 |
| 控制环 P99 | — | — | — | **~0.55 ms（与 v5 持平；新增检查全为 O(1)）** |

**通信开销**：多视角仅传融合后的占据摘要与相机健康签名（原始图像不出端）；证书共享需签名 + mint 元数据（~0.3 KB/证书）；能耗模型与 ρ/T_fresh 为低频下发。舰队层面：低电量站可将「预认证计算」交给有盈余的同伴，但**接收方必须按本地状态重新校验 freshness**（禁止跨状态直接复用）。

**续航收益来源**（不是靠跳过门）：
- 证书缓存命中：避免重复 VACK/BCK 全量计算，实测命中率 ~63%。
- 能量感知提议：候选先天落在低能耗、高边际区域，减少无效认证。
- 漂移感知重解：BCK 仅在 d_G > ρ 时重解，其余 O(1) 内插。
- 证书背包：把有限能量优先投给「边际/焦耳」最高的候选（引理 45）。

## 4. 正确性论证（增量更新）

### 引理 45（证书背包 1/2 近似）

**陈述**：完整认证计划是 0/1 背包（价值 = certified_margin，重量 = 能耗）。分数松弛的密度贪心最优；0/1 下 max(密度贪心, 单件最优) ≥ OPT/2。∎

### 定理 9（能量单调收缩）

**陈述**：Exec_v6(E) = S_0 ∪ {x : ∃ 完整认证计划, c ≤ E}，S_0 ⊆ Exec_v5。则 E1 ≤ E2 ⇒ Exec_v6(E1) ⊆ Exec_v6(E2) ⊆ Exec_v5，且 Exec_v6(0)=S_0≠∅。

**证明**：可行计划集合关于 E 单调不减；S_0 与 E 无关；完整认证必经七门，故进入者已在 Exec_v5。∎

**诚实边界**：该定理保证的是「可行认证集」的单调性；实际调度只实现其中一个前缀子集，故**实际执行集 ⊆ 定理集合**（不会更大，但可能更保守）。

### 定理 10（证书时效收缩）

**陈述**：无重认证时 Exec_v6(t) 关于 t 单调不增。

**证明**：fresh 的年龄项随 t 单调减；漂移项在漂移增长时单调减；删除操作只减不增。∎

### 定理 11（多视角保守精化）

**陈述**：若 kc_cov^6 = kc_cov^5 ∧ kc_mv 且 γ_mv ≥ 1，则 Exec_v6 ⊆ Exec_v5；多视角嵌入只进提议条件，不改边界（定理 6）。

**证明**：新增合取项只缩交集；γ_mv ≥ 1 按定理 5 只缩；提议无关性复用定理 6。∎

**诚实边界**：多视角「恢复被遮挡自由空间」的吞吐收益为经验性，不作为定理承诺；一旦视角标定漂移，kc_mv 可能系统性误紧（可用性风险）或误松（安全风险，靠保守融合兜底）。

### 定理 12（续航-覆盖可行性）

**陈述**：漂移速率 ≤ v_max、证书半径 ρ、单次全量重认证能耗 c、时域 T 下，连续认证覆盖可行 ⇔ E ≥ c·T·v_max/ρ；一般覆盖比例 = min(1, E·ρ/(c·T·v_max))。

**证明**：单证书有效期 ≤ ρ/v_max ⇒ 刷新次数 ≥ T·v_max/ρ ⇒ 能耗下界；周期 Δ=ρ/v_max 的刷新策略达到下界，故充分。∎

### 定理 v6（资源-感知双重收缩，总装）

**陈述**：在 v5 假设 (B1)~(B7) 及新增 (B8) 电量估计为真实剩余能量的下界、(B9) 多视角外参在健康签名有效期内误差 ≤ δ_mv 下：
(i) Exec_CADVS-v6 ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29；
(ii) 能量单调：E1 ≤ E2 ⇒ Exec_v6(E1) ⊆ Exec_v6(E2)（定理 9）；
(iii) 时效单调：无重认证时执行集随时间收缩（定理 10）；
(iv) 多视角只缩：γ_mv ≥ 1 且保守融合（定理 11）；
(v) 续航-覆盖权衡由定理 12 给出，未覆盖时段退 S_0；
(vi) 提议与感知精度提升只影响「找到高边际候选的概率」，不改变边界（定理 6）。

**证明**：(i) 同门 + 只加合取条件 + 只紧调制；(ii)(iii)(iv)(v) 分别由定理 9、10、11、12；(vi) 由定理 6。∎

**诚实声明**：(B8) 电量估计本身可能高估（温度/老化/负载模型误差），一旦高估则定理 9 的前提失效——这是本轮最大风险的根源；(B9) 多视角外参漂移与遮挡会让保守融合过度拒绝，造成「安全但不可用」；(iii) 漂移检测漏报会让过期证书继续有效，等价于 fail-open；(iv) 能耗模型 c_i 的误差会破坏背包近似的价值排序，但不破坏 fail-closed（最坏只是少认证）。

## 7. 本轮最大风险（最终确认）

**一句话**：**证书经济学的计量可信性**——整套收缩论证把安全寄托在「电量估计」与「状态漂移检测」这两个新的信任根上；若电池模型系统性高估剩余能量，或漂移检测漏报使过期证书被误判为新鲜，本应收缩的执行集就不会收缩，fail-closed 在资源层退化为 fail-open（系统带着过期证书、在电量将尽时继续动作）；对抗者还可通过耗尽能量实施「安全内核拒绝服务」。
