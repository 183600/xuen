# 灵感驱动研究循环 · UniBot 创新点研究 第 3 轮；本轮灵感：「通用机器人」×「模型蒸馏」

> 承接第 2 轮清单 v1.1（I1–I9）；纪律不变：先核实赛事事实再立论；每个创新点过「计分轴对齐、单模型边界、部署预算」三道闸；清单只做增量深化与修剪。本轮主线：**把「单模型」从约束读成杠杆——用蒸馏把离线专家农场压进一个可部署通才。**

**本轮最重要的核实结论**：把「单模型」误读为「只能训练一个模型」是普遍但错误的；规则只在你**对外服务的那一次前向**上要求单模型。于是「训练 32 个专家、蒸馏成一个学生」**在规则上天然合规**，且比 I3/I9 的「运行时混合推理」合规风险低得多（后者仍需书面确认）。这是本轮所有立论的支点。

## 1. 直觉与动机（两个灵感的碰撞）

**直觉 0（先纠错）：单模型是「答卷张数」，不是「家教人数」。**
高考只收一份答卷，但不限制你请多少家教；蒸馏就是把家教的知识压进考生一个人脑子里。多数队伍把「单模型」当成「只能练一个模型」，于是被迫在一个学生里硬塞 32 个任务，承受任务干扰与弱任务洼地（P1）——这可能是「榜首 <30%」的一个结构性解释。

**直觉 1（通用机器人）：通才不是「每个任务都学一点」，而是「每个任务都接近专家、却共享同一套参数与表征」。**
直接共训 32 任务 = 让 32 个目标在一个损失里互相拉扯，容量被平均化，弱任务拖垮均分。通用机器人的正确形态是**被压缩的专家集合**：先让每个技能家族各自逼近上限（教师），再蒸馏进一个共享基座的学生。反直觉点：**蒸馏的信息瓶颈是特性不是缺陷**——学生被迫只保留跨任务可复用的决策结构，反而可能比教师泛化更好（distillation as regularization）。官方 WLA-1.0 已宣称「一模型 64 任务」（F22），说明通才是官方方向；我们的先手在**构造方式**，不在方向本身。

**直觉 2（模型蒸馏）：蒸馏不是「压缩」，是「把昂贵的离线智能摊销到廉价的一次前向」。**
三类蒸馏，各自精准命中一个旧痛点：
- **(a) 专家→通才（行为/容量蒸馏）**：32 个（或 6–8 家族）LoRA 专家各自接近上限，学生一次前向复现「路由后的专家」→ 直打 P1 弱任务 + 单模型约束。
- **(b) 规划→反应（摊销规划蒸馏）**：把 I7 世界模型的 O(K) 次 rollout 择优，蒸馏成学生 O(1) 前向 → **结构性消除 I7 的延迟风险，同时保留其收益**（离线教师不进计分通道）。
- **(c) 多步→少步（一致性/渐进蒸馏）**：流匹配动作头从 T 步去噪蒸到 1–4 步 → 直打 I6 的 66ms 预算。

**三者统一（本轮核心论点）**：I1/I2/I5/I9 都在「造更强的教师/数据」，但它们的产物目前全被塞进一个**直接共训**的学生，容量与干扰互相打架——数据侧投入没有「变现通道」。本轮补上的蒸馏层就是这个压缩器：**教师农场负责「学得会」，蒸馏负责「装得下、跑得快、泛得开」。** 结论升级：中期胜负手 = **数据引擎 × 蒸馏压缩器**；前者决定上限，后者决定能否在单模型 + 延迟预算内**兑现**上限。

## 1.5 严谨定义（先直觉、后形式）

**定义 1（通才策略）**：单一参数化策略 π_θ(a|o,ℓ)，把观测 o 与指令 ℓ 映射到动作 chunk 分布，用一个部署参数集、每步一次前向服务全部任务；「单模型」即推理时 |{θ}|=1。

**定义 2（教师农场）**：离线教师集合 {π_T^k}_{k∈K}，K = 技能家族 ∪ {nominal, planner}；教师可大、可慢、可多，但**只允许存在于训练**（PR6）。

**定义 3（路由）**：ρ: ℓ ↦ K（或 K 上的软分布）。硬路由 = 任务→家族；软路由 = 家族混合，用于跨族任务。

**定义 4（行为蒸馏）**：min_θ E_{(o,ℓ)~D}[ d(π_θ(·|o,ℓ), π_T^{ρ(ℓ)}(·|o,ℓ)) ]，d 对离散动作为 KL、对连续速度场为流匹配损失。

**定义 5（摊销规划蒸馏）**：教师规划器 P 在状态 o 以世界模型做 K 次长度 L 的 rollout 取 a\*=argmax E[R]；学生 min_θ E[−log π_θ(a\*|o)]。推理复杂度从 O(K·L) 降到 O(1)——这是 I7 的合规化转生。

**定义 6（一致性蒸馏）**：设多步积分 T 得到 a_0^T；学习 θ' 使少步 S≪T 的积分 f_{θ'}(x_t,t) 匹配教师轨迹：min E_{x_t,t}[‖f_{θ'}(x_t,t) − a_0^T‖²]（或沿教师轨迹做速度匹配）。

**定义 7（可蒸馏性）**：任务 τ 在容量 C 下 ε-可蒸馏，若存在 |θ|≤C 使 L_distill(θ;τ)≤ε 且 success(π_θ,τ) ≥ success(π_T,τ)−δ。经验上由 **teacher–student gap 曲线的斜率与平台**预测：gap 不收敛即「容量瓶颈」。

**定义 8（鲁棒性蒸馏假设，Q11）**：教师 π_T 在增广分布 P_aug 上训练，学生 π_S 仅在 P_clean+εP_aug 上蒸馏；假设 risk_{P_aug}(π_S) 逼近 risk_{P_aug}(π_T)，且样本复杂度低于直接在 P_aug 上训练 π_S。**这是本轮最值得下注、也最需要 L0 证伪的科学假设。**

## 2. 对第 2 轮痛点的增量修订

- P1（弱任务支配）：新增「容量分配」视角——蒸馏按**教师间分歧**加权，把学生容量优先分给难任务/高分歧区，而非只靠数据重加权（I2）。
- P6（部署预算）：新增少步一致性蒸馏，把「流匹配推理步数」变成可优化变量（I6 v3）。
- P7（世界模型延迟）：I7 从「测试时前瞻」**转型为离线规划教师**，延迟风险结构性消除（I7 v2）。
- P8（示教质量）：教师用高质量子集训练；学生蒸馏时对低质教师输出降权。
- 新增 **P9（容量瓶颈/误差继承）**：多教师知识可能压不进单学生；教师错误会被学生「自信地」继承——这是本轮最大新风险。

## 3. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

- **Q9（可蒸馏性）**：32 任务/家族专家的知识，在「共享基座 VLM + 单动作头」学生里能压到什么程度？用什么早期信号（gap 斜率、教师分歧、任务相似度）预测「某任务不可蒸馏」？
- **Q10（蒸馏目标组合）**：行为/特征/规划/一致性四类目标如何配比，才能同时改善弱任务、泛化与延迟？哪些目标互相冲突（如一致性蒸馏伤害多模态动作多样性）？
- **Q11（蒸馏即正则）**：蒸馏能否让增广/孪生/合成数据带来的鲁棒性以更低样本成本迁移给学生（定义 8），从而减少学生对 I1 巨量增广数据的直接训练依赖？

## 4. 设计原则（新增 PR6）

- **PR6 蒸馏合法性原理**：一切「多模型/多专家/世界模型/检索」只允许存在于**离线训练**；计分通道上永远只有一个前向的学生模型。任何想上计分通道的「额外模型/规划/检索」必须先证明**能蒸馏进学生**，否则裁掉。这把 PR2 的模糊边界变成硬约束：I3/I9 从此必须服从「能蒸馏才算数」。
- PR1–PR5 保留（第 1/2 轮 §4）。

## 6. 本轮最大风险

**一句话**：蒸馏的整个赌注押在「专家知识能压进单学生」上——若容量瓶颈成立（32 个专家的总容量远超一个可部署学生），学生会同时丢掉专家精度与直接共训的简单性，且教师错误会被学生「自信地继承」、极难从外部察觉；因此必须先跑**可蒸馏性 L0 诊断**（每任务 gap 曲线），再决定是否放量，而不是先建 32 个教师。

## 7. 下轮迭代计划（深化与修剪，不推倒）

- **深化**：I10（可蒸馏性诊断的形式化 + 6–8 家族教师农场最小原型）；I6（少步一致性蒸馏，先核实官方动作头的默认步数）；Q11（鲁棒性蒸馏 vs 直接增广训练的首个 L0 对照）。
- **修剪**：I7 由「测试时前瞻」降格为「离线教师」，若 WMA-0 rollout 太弱则只保留为 I5 数据生成器；I3/I9 的运行时路径全部改为「训练期教师」。
- **待核实**：官方 WLA 动作头的默认去噪步数与是否已有少步支持；N 值；步骤分精确公式；组委会对「离线多模型训练 + 单模型部署」的书面确认（README 已强支持，但仍建议留证）。

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2）

> 检索日期：2026-11-26（第 1 轮）、2026-11-27（第 2/3 轮）；来源见 §5。承接 v1.1：新增 I10，I7 转型，I1/I2/I3/I5/I6/I9 深化，I4/I8 维持。核心纪律：**计分通道只跑一个学生前向（PR6），所有教师/世界模型只活在离线训练。**

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I1 v3 考纲校准增广引擎（+ 教师专用增广）★★★★★
- **动机**：（v2 保留）计分的 320 次真机评测每次都在 5 轴上偏离训练分布（P2/F2），泛化缺口是全局乘性损失。
- **本轮深化（通用机器人/蒸馏）**：增广数据从「直接喂学生」改为「优先喂教师」——教师吸收 P_aug 的多样性，学生只在 P_clean + 少量增广上做蒸馏，继承鲁棒性（定义 8 / Q11）。收益：学生训练算力与磁盘需求下降；增广分布不必与最终提交强绑定。保留 v2 的考纲卡与剂量-响应。
- **与现有方案差异**：盲目增广 vs 考纲校准（v2）→ 再加「增广经教师中转」（v3）。
- **技术可行性**：高（考纲卡半自动；蒸馏标准）。
- **所需资源**：分割/inpainting 1×24GB；增广产物主要供教师农场。
- **落地步骤**：①32 张考纲卡；②背景/干扰物放量喂教师；③学生端做「干净 + 10% 增广」蒸馏；④L0 对照：直接增广训练 vs 蒸馏继承（Q11 判据：risk_{P_aug} 差 ≤5%）。
- **风险**：鲁棒性蒸馏不成立（学生继承不到）→ 回退 v2 直接增广训练；考纲卡与真实评测仍有偏差（同 v2）。

### I2 v3 数据引擎 2.0+：孪生迁移 + 加权共训 + 蒸馏正则/核心集 ★★★★★
- **动机**：单模型平均分被最弱任务支配（P1）；示教语料与质量双重浪费（P8）；负迁移与遗忘。
- **本轮深化（示教学习 + 蒸馏）**：
  1. **孪生语料入训**（同 v2，F10）：110 任务按技能孪生表选择性入训。
  2. **官方 loader 加权 patch**（同 v2，F11）：32 全量 + 孪生半权重 + 远任务 ≤5%。
  3. **示教质量加权**（同 v2）：进度效率 × 平滑度 × 成功裕度，剪最差 10%。
  4. **标称教师 KL 防遗忘（新）**：固定一个「只在 32 任务标称数据上训」的 nominal teacher；吃孪生/增广/合成数据时加 KL(π_nominal‖π) 正则，防止漂移与负迁移。
  5. **轨迹核心集蒸馏（可选，低优先）**：用教师对 110 语料的「可迁移性评分」选代表轨迹子集，压磁盘、降负迁移；不作主线（数据集蒸馏在机器人轨迹上尚不成熟）。
- **与现有方案差异**：数据重加权只能「多给」，KL 正则能「拉住」；核心集把 1–2TB 的暴力共训变成有选择的迁移。
- **技术可行性**：高（KL 正则一行损失；核心集需一次离线评分）。
- **所需资源**：孪生子集 ≈1–2TB + 32 任务 ≈2TB；nominal teacher 额外一次训练（可复用 I10 教师农场）。
- **落地步骤**：①孪生表；②loader patch + 单测；③nominal teacher；④KL 权重扫描（L0）；⑤核心集评分；⑥族级负迁移消融。
- **风险**：KL 权重过大抑制新知识（λ 扫描 + 早停）；核心集选择偏差；相机配置不一致（同 v2）。

### I3 v3 接触任务族关键点视觉伺服（维持 + 伺服教师蒸馏）★★★★
- **v1/v2 六要素保留**：通用 chunk 策略负责接近段、几何伺服负责接触段；`ee` 控制空间 + per-step 调用天然支持；关键点用开放词汇检测零训练起步；触发滞回 + 低置信回退。
- **本轮关键改造**：不再做「运行时通用策略 + 伺服混合推理」（PR2 边界风险），而是把几何伺服当作**训练期教师**——在仿真/回放中由伺服产生接触段动作，蒸馏进学生的接触段注意力与动作头；推理纯端到端单模型。I3 从「合规待确认」变成「合规确定」。
- **与现有方案差异**：运行时混合（有风险）→ 训练期教师（PR6 合规）。
- **技术可行性**：中-高；伺服在仿真里易得标签；蒸馏标准。
- **所需资源**：仿真/回放 1×GPU；蒸馏并入 I10。
- **落地步骤**：①伺服教师产出接触段标签；②接触段加权蒸馏；③L0 对比「混合推理 vs 蒸馏」在 6–8 任务上的成功率。
- **风险**：伺服教师与真实接触动力学有 sim-real gap → 只学「几何接近策略」，不学力控细节；关键点检测误差。

### I4 人手干预感知门控 + 自适应 chunk ★★★★（维持）
- **六要素同 v2**：手部检测 + `obs_delta_indices` 历史栈做干预判别（<50ms）；状态机 INTERFERED→停持→重估→续做（PR3）；干预态短 chunk / 稳定态长 chunk。
- **本轮补充**：WMA-0 部署参数（15Hz、horizon 16，F12）作官方参照——干预态 chunk 取 4–6 步、稳定态 8–16 步，待真机标定。本轮不改主线，避免摊薄。

### I5 v3 非标称示教合成 + 得分点对齐恢复（+ 两级蒸馏）★★★★
- **动机**：步骤分 = 官方得分点制（F17，每任务满分 100）；超时仍按进度计步骤分（F3）；数据集全成功、无失败示教（P8）。
- **本轮深化**：保留 v2 的扰动重放 / 跨段缝合 / 世界模型生成 / 得分点过滤；新增 **两级蒸馏**——合成数据**不直接混入主学生**，先训「恢复教师」，再蒸馏进主学生。好处：合成分布污染被教师层吸收，学生只学「何时需要恢复」的可复用结构；与 I10 教师农场天然合流。
- **与现有方案差异**：合成数据直灌（v2）→ 教师中转（v3）。
- **技术可行性**：中-高（纯数据工程 + 轻量里程碑检测器）。
- **所需资源**：1×24GB；数据工程 2 人周；检测器 1 GPU 日/族。
- **落地步骤**：①得分点逆向（wiki + JS 端点）；②3 弱任务（PlugCharger/ZipUp/PourOutMedicine）合成；③恢复教师；④蒸馏进主学生；⑤真机 A/B（恢复成功率、步骤分）。
- **风险**：合成-真实偏离分布失配；教师把合成伪影当知识教给学生（得分点门禁 + 5% 人工抽检）。

### I6 v3 确定性低延迟部署 + 少步一致性蒸馏 ★★★★★
- **v2 六要素保留**：共享 backend + 每端口独立队列/状态隔离、fp8/INT8、torch.compile/CUDA Graph、obs 预取、`image_resize`、断线重连 + 健康探针（PR4）。
- **本轮深化（蒸馏）**：流匹配动作头默认多步去噪；用渐进/一致性蒸馏把 T 步压到 S∈{1,2,4} 步，直接兑现 15Hz→66ms 预算（F12）。给出 **NFE–成功率 Pareto**，而非只报单点延迟。
- **与现有方案差异**：只做工程加速（v2）→ 算法级少步蒸馏（v3）。
- **技术可行性**：高（一致性蒸馏成熟，但需防多模态坍缩）。
- **所需资源**：蒸馏 1×24GB；评测 NFE 扫描；2×A100 80G 共享 backend。
- **落地步骤**：①核实官方动作头默认步数；②T→S 渐进蒸馏；③Pareto 扫描；④p99 门禁 + 动作多样性回归。
- **风险**：少步蒸馏损伤多模态/精细接触精度 → 用 Pareto 选点、接触任务不激进压步；官方动作头若不支持少步采样则回退工程加速。

### I7 v2 世界模型：从「测试时前瞻」转型为「离线规划教师」★★★★（↑，风险↓）
- **转型动机**：v1/v2 的测试时 O(K) rollout 直接吃延迟预算，风险高、易被裁。
- **新定位**：世界模型只在离线做规划教师——对高险节点做 K 次短 rollout 择优得到 a\*，把 (o, a\*) 作为 I10 的规划蒸馏目标；推理时学生 O(1) 前向，无任何额外计算。
- **与现有方案差异**：测试时前瞻（昂贵）→ 训练期摊销规划（免费推理）。
- **技术可行性**：中；依赖 WMA-0 rollout 质量（F15）。
- **所需资源**：离线 rollout 8×A100 数日（与 I10 教师农场共用）。
- **落地步骤**：①短 horizon rollout；②规划标签 + 得分点验证；③蒸馏进学生；④若 rollout 太弱 → 降级为 I5 数据生成器。
- **风险**：世界模型误差使教师规划本身错误，学生学到坏计划 → 短 horizon + 得分点验证 + 仅在「规划增益 L0 为正」的节点启用。

### I8 v2 评测运营闭环 + 分级消融注册表 ★★★★（维持，注册表加蒸馏维度）
- **v2 框架保留**：L0 in-silico / L1 分数因子 / L2 真机确认；注册表记录「离线预测 vs 真机增益」，相关性 >0.6 的代理才可单独准入 L2。
- **本轮新增记录项**：**蒸馏增益**（学生 vs 同数据同算力直接共训）、**可蒸馏性预测 vs 实际 gap**、**NFE–成功率**。
- **风险**：离线代理与真机增益相关建立慢（同 v2，用已知历史结果回填）。

### I9 v2 reset 期检索类比 → 可蒸馏的先验 ★★★★
- **v2 保留**：`reset()`（每 episode 一次，F18）做物体嵌入检索，命中则取动作先验；距离阈值门控。
- **本轮深化**：把检索从「推理期组件」改为「训练期教师」——检索到的动作先验作为教师信号蒸馏进学生（物体嵌入→动作参数的映射进权重），推理时可选保留检索（低开销）或完全去掉。若去掉则彻底合规；若保留，作为 PR6 下唯一允许的轻量推理组件，仍需书面确认。
- **与现有方案差异**：推理期检索（需确认）→ 训练期蒸馏（默认合规）。
- **技术可行性**：中-高（同 v2 + 蒸馏）。
- **所需资源**：嵌入 1×GPU 日 + FAISS；1 人周。
- **落地步骤**：①物体-技能库；②检索教师；③蒸馏进学生；④A/B：有/无推理期检索。
- **风险**：误检索被蒸馏进权重后难以门控 → 训练时用距离阈值过滤、只蒸馏高置信样本；未见物体嵌入不敏感（同 v2）。

### I10 专家农场→单学生多目标蒸馏（新，本轮核心）★★★★★
- **动机**：单模型部署约束（F20/F21）+ 弱任务支配（P1）+ 延迟预算（P6）+ 世界模型风险（P7）。四个看似独立的问题，收敛为同一个「压缩」动作。
- **设计**：
  1. **教师农场**：一个共享基座 VLM（UnifoLM-ER-1/Flow，F16/F23）+ 6–8 个技能家族 LoRA 专家 + 1 个 nominal 通才教师 + 1 个 planner 教师（I7）。LoRA 使教师便宜（F11）。
  2. **学生**：一个通才（LoRA 或全参动作头）= 唯一提交实体。
  3. **四类蒸馏目标**：行为（路由教师）、特征（中间层）、规划（I7）、一致性（I6 少步）。配比见 §1.2。
  4. **路由**：指令→任务→家族；跨族任务用软路由（家族混合）。
  5. **容量分配**：按教师间分歧（认知不确定度）与 teacher-student gap 加权，把学生容量优先给难任务/高分歧区。
  6. **防遗忘**：对孪生/增广/合成样本加 nominal teacher KL（与 I2 共用）。
  7. **可蒸馏性诊断**：每任务画 gap 曲线；不收敛 → 标记「容量瓶颈」→ 该族加 soft-MoE 容量槽或直接数据回灌（§1.4）。
- **与现有方案差异**：直接共训 vs 专家蒸馏；单模型推理不变；合规上只动训练（PR6）。
- **技术可行性**：中-高。LoRA 教师便宜；蒸馏损失标准；风险在容量与路由。
- **所需资源**：教师农场 8×A100 数日（可复用 I2/I5/I7 产物）；学生每轮 1–2 GPU 日；推理 2×A100 共享。
- **落地步骤**：①家族分类法（LLM 初筛 + 人工）；②训 6–8 LoRA 专家 + nominal；③四目标蒸馏学生；④可蒸馏性诊断；⑤L0（教师农场 vs 直接共训，匹配算力）→ L1 → L2。
- **风险**：**容量瓶颈**（最大）——soft-MoE 容量槽、按族逐步加教师、gap 诊断早停；**教师误差继承**——得分点验证教师输出、集成多教师投票、低置信样本降权；**路由错误**——软路由 + 指令解析兜底。

## 1. 关键伪代码

### 1.1 教师农场与路由
```python
FAMILIES = {  # 6–8 家族，示意（LLM 初筛 + 人工校对，勿照抄）
  "insert":  ["PlugCharger","PlugInEthernet","DisconnectEthernet","Unlock"],
  "pour":    ["PourOutMedicine","SyringeWaterTransfer"],
  "pack":    ["PackPhone","PackBag","PackDoll","StoreEarphones","StorePaddle"],
  "sort":    ["ColorArrangement","FruitSorting","ConveyorSorting","FruitCollection"],
  "fold":    ["FoldTowel","ZipUp","ArrangePlates","ArrangeTestTubes"],
  "stack":   ["StackBowls","PaperCupStacking","StoreCups","HangCup"],
  "assemble":["OrganizeTools","ToolboxStorage","SpellRobot","OrganizePencilCase"],
  "place":   ["PlacePhotoFrame","RemovePinnedNote","OrganizeBookshelf","OrganizeStationery"],
}

def train_teacher_farm(base_vlm, data):
    T = {"nominal": finetune(base_vlm, nominal_only(data))}
    for fam, tasks in FAMILIES.items():
        T[fam] = finetune_lora(base_vlm, subset(data, tasks) + twins(fam))
    T["planner"] = load_world_model_teacher()      # I7，离线 rollout 择优
    return T

def route(instruction):
    return FAMILIES.inv[task_of(instruction)]       # 指令 -> 任务 -> 家族
```

### 1.2 多目标蒸馏损失
```python
def distill_step(student, T, batch, cfg):
    o, l, a = batch
    fam = route(l)
    with torch.no_grad():
        t_act  = T[fam].flow(o, l)              # 行为：路由教师
        t_feat = T[fam].features(o, l)          # 特征：中间层
        t_plan = T["planner"].best_action(o, l) # 规划：I7 离线择优
        t_nom  = T["nominal"].flow(o, l)        # 防遗忘
        w = 1 + cfg.beta * teacher_disagreement(T, o, l)  # 容量按分歧分配
    L_beh  = flow_matching_loss(student, t_act) * w
    L_feat = mse(student.features(o, l), t_feat)
    L_plan = flow_matching_loss(student, t_plan)
    L_reg  = kl(student.flow(o, l), t_nom) if is_aug_or_synth(o) else 0.0
    L_cons = consistency_loss(student, o, l)    # §1.3
    return L_beh + cfg.l1*L_feat + cfg.l2*L_plan + cfg.l3*L_reg + cfg.l4*L_cons
```

### 1.3 少步一致性蒸馏（I6）
```python
def consistency_distill(student, teacher, x_T, cfg):
    with torch.no_grad():
        traj, v_teacher = teacher.integrate(x_T, steps=cfg.teacher_steps)  # 如 16
    t = sample_timestep()
    x_t = traj(t)
    return mse(student.velocity(x_t, t), v_teacher(t))   # 学生少步即匹配教师轨迹
    # 评测：S in {1,2,4,8} 的 NFE-成功率 Pareto
```

### 1.4 可蒸馏性诊断（I10 的止损器）
```python
def distillability_report(student, T, task, ckpts):
    gaps = [eval_success(T[fam_of(task)], task) - eval_success(s, task) for s in ckpts]
    slope = linear_fit(gaps)
    if gaps[-1] < TAU_GAP and slope < 0:  return "distillable"
    return "bottleneck"   # -> 加 soft-MoE 容量槽 / 该族数据回灌 / 停止加教师
```

## 2. 实验设计（分级消融协议 v3）

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0 | **可蒸馏性 gap 曲线**；四类蒸馏目标消融；NFE–成功率 Pareto；**鲁棒性蒸馏 vs 直接增广（Q11）**；教师农场 vs 直接共训（匹配算力） | 离线（免费） | 学生 gap 收敛；Q11：risk_{P_aug} 差 ≤5%；农场不劣于共训 |
| L1 | 路由（硬/软）× 容量分配（均匀/分歧加权）× 防遗忘 KL（on/off）部分析因 | 离线+少量真机 | 主效应显著的 ≤3 组合进 L2 |
| L2 | top 候选真机：≥2 任务 × 各 2 次；对照 = I2 直接共训 | 单任务通道 | 真机成功率/步骤分 ≥ 直接共训；p99<40ms |
| 门禁 | PR4：run_client 全流程 + p99 + 动作健康度 + 动作多样性回归 | 本地 stub | 0 拒绝动作、p99<40ms、少步不坍缩 |

**首个决定性实验（下轮第一件事）**：在 4 个代表任务（弱：PlugCharger/ZipUp/PourOutMedicine；强：HangCup）上，用**匹配算力**比较「6–8 家族 LoRA 教师→蒸馏学生」vs「同数据直接共训学生」。若蒸馏在弱任务上无增益或 gap 不收敛 → I10 立即降级，避免把预算烧在 32 个教师上。

**首批 L2 排队**：①I10 匹配算力对照 → ②I6 少步 Pareto → ③Q11 鲁棒性蒸馏 → ④I7 规划教师增益。

## 6. 本轮最值得押注（一句话）
