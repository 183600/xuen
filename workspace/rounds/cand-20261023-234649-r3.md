# 第 3 轮 · RUBICON 4.0：从“部件分割”到“谓词残差”

## 0. 本轮先核实，再动脑

这一轮我没有先想架构，而是先把“哪些事实已经变了”查清楚。四个发现直接改变了判断：

1. **官方规则原文拿到了**：Feishu 手册 1.1/1.2/2.1/2.2 可读。仅通才模型赛道；**所有任务须基于同一模型完成，不得混合多个模型一起测试**；32 任务 × 10 次；5 类泛化各 2 次；单次真机最多 180 秒；按 32 任务**总平均成功率**排序，成功率相同才看**总平均步骤分**，再相同看提交日期；选手自部署，平台远程调用；单任务调试不计分。[S4]
2. **公开榜仍是占位，不是真实排名**：页面 UI 仍显示“即将发布 / Coming Soon”；`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`；通过 `r.jina.ai` 抽出的隐藏表仍是 MolmoAct2 29.7%、WALL-OSS 28.5%、DreamZero 27.9% 这一组数字，与用户简报完全一致。[S2][S3] 这组数字只能当“难度直觉”，不能当“谁强谁弱”的证据。
3. **官方基线已经开源，而且就是为这个赛事准备的**：UnifoLM-WLA-1.0-Base，6B，约 2500 小时真机数据，单模型 64 任务，Apache-2.0，9 月 28 日放出权重 + 微调/LoRA/action-expert 代码；另有 UnifoLM-ER-1（4B 空间推理 VLM）和 ER-Flow（4B action expert）。[S9][S10][S11][S12] 这意味着“从零训一个 6B VLA”不再是理性选择；正确做法是**在 WLA 上加一个可验证的状态接口**。
4. **“语音合成”在本赛没有直接入口**：G1 确实有 4 麦克风阵列、5W 扬声器和 TTS SDK；但提交 API 的观测目录只有 4 路 RGB、proprio 和**文本** `observation.language`，没有音频键。[S5][S13][S14] 所以语音输入、语音输出、语音克隆都不能进主策略；能用的只有“离线 TTS→ASR 指令增广”和“TTS 时长/韵律→动作时域”的类比迁移。

另外两个工程事实也很关键：

- 数据集 32 个 repo、官方页称 32,000+ episodes / 169 小时、HF collection 汇总约 33,276 episodes；4 路 480×640@30fps、AV1、**无音轨**；`meta/tasks.parquet` 每个任务有 **5 条英文复述**（用 `@` 分隔）；Apache-2.0。[S6][S7][S8]
- WLA 默认 **action chunk = 30，target_fps = 30**，也就是一次预测约 **1 秒**的动作；统一动作 54 维、状态 60 维。[S15] 固定 1 秒 chunk 对自由空间很高效，但对“插头最后几毫米”和“人手突然把毛巾翻开”太慢。这是“续航/时域”真正的切入点。

## 1. 三个灵感词，只有两个半能用

### 1.1 「单模型多任务」：不是“32 合 1”，而是“共享中间语言”

规则的字面要求是“一个模型跑 32 个任务”。但真正的技术问题是：**32 个任务之间共享什么？**

- 如果共享的只是一个大 VLA 的隐空间，模型仍然是在做 32 路隐式分类；任务一多，梯度冲突、灾难性遗忘、语言过拟合都会出现。
- 如果共享的是一个**谓词/关系目标空间**，32 个任务就变成“同一组谓词的不同组合”。例如：
  - 挂杯 = `hanging(cup, hook)` + `aligned(cup_handle, hook)`
  - 插插头 = `grasped(strip)` + `grasped(plug)` + `inserted(plug, socket1)`
  - 叠毛巾 = `folded(towel)` + `on(towel, side)`
  - 分拣 = `grasped(item)` + `sorted(item, rack_category)`
  - 叠碗 = `stacked(bowl2, bowl1)` + `stacked(bowl3, bowl2)`

这就是本轮的第一个主判断：**单模型多任务的最优中间表示不是“任务 ID”，也不是“纯语言”，而是“目标谓词 + 当前信念 + 二者之差”**。模型不需要知道“这是 T16”，只需要知道“目标是把毛巾叠好，当前毛巾还没叠好，差的是 fold 谓词”。这既满足“不喂 task id”的合规要求，也天然支持未见物品和人为干扰。

### 1.2 「续航能力」：拆成服务续航、语义续航、时域续航

上一轮把续航拆成“服务续航 + 语义续航”，是对的，但漏了第三个：**时域续航**。

- **服务续航**：N 个端口共享一个 6B 后端；p99 延迟、显存、热节流、崩溃恢复、每端口状态隔离。
- **语义续航**：谓词信念跨遮挡、跨阶段、跨人为干扰保持；人手离开后重新 grounding，而不是从零开始。
- **时域续航**：180 秒预算内，什么时候用长 chunk 抢时间，什么时候用短 chunk 保精度；任务做到一半被撤销，剩余时间还够不够修复。

固定 chunk=30（1 秒）是“时域续航”的反例：自由空间可以更长，接触阶段必须更短，人手进入工作区必须立刻缩短。于是有了 **AH-TP（Adaptive Horizon + Temporal Prosody）**：同一个 checkpoint 额外预测“当前 chunk 的有效执行长度”和“下一个谓词还要多久”，运行时用 `min(H, h_t, deadline_steps)` 执行。它不是第二个模型，也不是在线 RL，而是把 TTS 里的“时长预测/韵律”迁移到动作时域。

### 1.3 「语音合成」：直接路径是死路，间接路径有两个

直接路径全部修剪：

- 不做音频编码器：API 没有音频输入。
- 不做语音指令：`observation.language` 是文本，且整段 episode 恒定。
- 不做机器人语音输出作为策略动作：评分不测，且可能干扰人为干扰协议。
- 不做语音克隆/情感 TTS：与成功率无关。

间接路径保留两个，但都降级：

1. **TTS→ASR 指令增广（P2）**：把 5 条官方复述用多音色、多语速、加噪 TTS 合成，再用 ASR 转回文本，得到带识别错误的指令变体；训练 goal compiler 的文本鲁棒性。已有机器人语音理解文献证明“噪声注入/ASR 错误增广”能提升语义解析鲁棒性。[S25]
2. **韵律→动作时域（P1，已并入 AH-TP）**：TTS 的 duration predictor 预测每个音素的时长；动作侧对应“每个谓词的持续时间 + 接触阶段的减速/强调”。这是本轮对“语音合成”最有价值的类比，不是语音本身。

预期收益要说实话：在没有音频输入的评测里，TTS/ASR 增广对成功率的直接贡献大概率是 **0–1pp**；它只是廉价的语言鲁棒性保险，不是主押注。

## 2. 本轮主判断：把 SPA-VLA 和 RPSM 合并成 GPR-VLA

上一轮的两个 P0 是分开的：

- **SPA-VLA**：部件分割蒸馏进单模型，解决“抓哪里/插哪里”。
- **RPSM**：可逆部件状态记忆，解决“被撤销后修复”。

它们各自都对，但合起来才完整。分开时，部件 token 只是感知特征，状态记忆只是外部模块；合起来可以变成一个**目标调节器**：

```text
语言 l ──► Goal Compiler ──► 目标谓词 z*
                                      │
4 视图 + proprio ──► Part Encoder ──► 当前信念 b ──► 残差 r = z* − b
                                      │
                                      ▼
                              Action Expert ──► 动作 chunk + 有效时域 h + 谓词时长 d
```

我把它叫 **GPR-VLA（Goal-Predicate Residual VLA）**。它的三个关键点：

1. **一个 checkpoint**：goal compiler、part encoder、belief tracker、action expert 全在同一计算图；离线 SAM3/PartSAM 只做教师，部署时不加载。
2. **不喂 task id**：目标谓词由语言 + 5 条复述学习得到；任务差异体现在 `z*`，不体现在任务编号。
3. **进度可逆**：`b_k` 允许 1→0；人手把毛巾翻开，`folded` 从 1 掉到 0，残差重新变正，策略只修复 `folded`，不重跑全程。

这比“再加一个 progress head”强，因为 progress head 只能告诉你“做到第几步”，GPR-VLA 告诉你“**哪个谓词被破坏了、该修复什么**”。这正好对准官方 `human_1/human_4` 的撤销式干扰：T16 翻开毛巾、T19 拉开拉链、T14 拧回盖子、T10 拔起插头、T27 拿走第二个碗、T24 把食物放回传送带起点。[S15]

## 3. 本轮修剪

| 保留/升级 | 理由 |
|---|---|
| WLA-1.0-Base + LoRA/action expert | 官方 6B/G1/64 任务/Apache-2.0，比从零训便宜且强 |
| 离线 SAM3/PartSAM 教师 | 只生成部件伪标签，不进运行时 |
| GPR-VLA（部件 + 谓词 + 残差） | 同时解决单模型多任务、未见物品、撤销恢复 |
| AH-TP（自适应时域 + 时长预测） | 对准 180s、固定 1s chunk、人手干扰 |
| 部件接触伺服 | 插头/网线/拉链/瓶盖/钥匙的最后几毫米 |
| Endurance Governor 2.0 | N 端口、p99、热/内存、语义记忆 |
| Compliance Compiler 2.0 | 单模型审计、无 task id、许可证、人机安全 |
| Task Portfolio 2.0 | 成功率优先，先消灭 0% 任务 |

| 修剪/暂缓 | 理由 |
|---|---|
| 在线 SAM3/PartSAM 级联 | 违反“单模型”精神，延迟也扛不住 |
| 独立 progress head | 谓词信念本身就是进度，且可逆 |
| 运行时外部 VLM planner（CycleVLA 式） | 第二个模型，合规风险高；要蒸馏进同一 checkpoint |
| 音频输入/语音输出/语音克隆 | API 无音频，评分不测 |
| 每任务 LoRA/模型合并 | 容易被审计为“多模型”；且 32 份权重不现实 |
| 从零训 6B | 数据/算力/时间都不划算 |
| 激进 waist/pivot | 成功率优先；默认静态，任务需要时小范围探针 |
| 完整 world model / 仿真 RL | P3；先做真实数据 + 谓词接口 |

## 4. 一句话押注

**把 32 个任务压成共享的谓词/关系目标空间，用单模型 VLA 输出“目标谓词 − 当前信念”的残差，再用自适应时域把固定 1 秒 chunk 变成“接触慢、自由空间快、被撤销就重开对应谓词”的闭环。**

# RUBICON 4.0 · 单模型谓词残差 + 自适应时域

> 检索/复核日期：**2026-10-23**。所有外部事实均标注来源编号；无法核实的地方明确写“未核实”。榜单分数只作占位，不作真实排名。

## A. 结论

本轮把上一轮的 SPA-VLA + RPSM 合并为一个更对准评分口径的主押注：

1. **GPR-VLA（Goal-Predicate Residual VLA）**：把 32 个任务压成共享的**谓词/关系目标空间**。语言 → 目标谓词 `z*`；4 视图 + proprio → 当前信念 `b`；动作专家条件在残差 `r = z* − b` 上。一个 checkpoint，不喂 task id，允许 `b` 从 1 回退到 0，因此人手撤销子目标后只修复被破坏的谓词。
2. **AH-TP（Adaptive Horizon + Temporal Prosody）**：同一个 checkpoint 预测当前 chunk 的有效执行长度 `h_t`、下一个谓词的持续时间 `d_k`、接触阶段的减速/强调。运行时执行 `min(H, h_t, deadline_steps)`：自由空间用长 chunk 省推理，接触/人手进入时缩到 1–2 步。
3. **Endurance Governor 2.0 + Compliance Compiler 2.0 + Task Portfolio 2.0**：分别解决 N 端口长时服务、单模型/许可证/人机安全审计、以及“先消灭 0% 任务”的调试预算分配。

**最重要的口径**：官方排序是总平均成功率优先，步骤分只是 tie-breaker；320 次试验在 p≈0.3 时标准误约 **2.56pp**，1–2pp 的差距基本是噪声。想把“排名更高”的概率做到约 80%，需要约 **3pp** 的真实优势；做到约 90% 需要约 **5pp**。所以本轮不追“更大的 VLA”，只追能显著抬高平均成功率的**状态接口 + 恢复能力 + 时域适配**。

**官方基线**：UnifoLM-WLA-1.0-Base（6B、约 2500h、64 任务、Apache-2.0、LoRA/action-expert 微调代码，2026-09-28 发布）是本赛最合理的起点。[S9][S10] 本轮所有训练方案都默认“在 WLA 上加接口”，而不是从零训。

**语音合成**：API 观测无音频，`observation.language` 是文本；因此语音输入/输出/克隆全部修剪。只保留两个间接落点：TTS→ASR 指令增广（P2）和 TTS 时长/韵律→动作时域（并入 AH-TP，P1）。预期直接收益很低，不作为主押注。

### B.5 评分数学与统计功效

设任务 `i` 的第 `j` 次试验成功为 `y_ij ∈ {0,1}`，步骤分为 `q_ij ∈ [0,100]`：

```text
S = (1/32) * Σ_i (1/10) * Σ_j y_ij          # 总平均成功率
Q = (1/32) * Σ_i (1/10) * Σ_j q_ij          # 总平均步骤分
rank: S desc, then Q desc, then submission_date asc
```

总平均成功率的近似标准误：

```text
SE(S) ≈ sqrt( (1/32^2) * Σ_i p_i(1-p_i)/10 )
```

当所有 `p_i≈0.3` 时：

```text
SE(S) ≈ sqrt(0.3*0.7/320) ≈ 0.0256 = 2.56pp
95% CI ≈ ±5.0pp
```

**真实优势与“排名更高”的概率**（正态近似，320 次试验）：

| 真实成功率优势 Δ | P(观测排名更高) |
|---:|---:|
| 0.5pp | 55.5% |
| 1.0pp | 60.8% |
| 1.5pp | 66.0% |
| 2.0pp | 70.8% |
| 2.5pp | 75.3% |
| 3.0pp | 79.3% |
| 4.0pp | 86.1% |
| 5.0pp | 91.2% |

**边际价值**：

```text
一个任务 +10pp  → 总平均 +0.10/32 = +0.31pp
全部 32 任务 +2pp → 总平均 +2.0pp
一个任务 +30pp  → 总平均 +0.94pp
```

所以：**先消灭 0%（一个 0% 任务相对 100% 损失 3.1pp、相对 30% 损失 0.94pp），再在 3–5 个短板上各拿 20–30pp，比在强任务上抠 1–2pp 更划算。**

**共同瓶颈**（按官方评分轴排序）：

1. **接触最后几毫米**：插头 prong、网线水晶头、钥匙、瓶盖、拉链、试管。头部双目在 1m 处只有厘米级精度；必须腕部近景 + 部件 centroid/normal + 相对位姿伺服。
2. **可逆状态**：官方 human 干扰会撤销已完成子目标；大多数 VLA/进度头假设单调推进，缺少“回退检测 + 定向修复”。
3. **长程状态**：4–5 检查点任务（T09/T15/T16/T17/T18/T22/T28）容易漏点、premature stop、失败不重试。
4. **时域**：固定 1s chunk 在自由空间省推理，但在接触/人手进入时反应太慢；180s 预算下，修复策略需要知道“还剩多少时间”。
5. **部署稳定性**：4 路视频、N 端口、长时并发；p99/热/内存会直接吃掉成功率。
6. **合规风险**：单模型、外部数据/模型、任务硬编码、许可证；一项不清可能归零。

**结论**：头部方案强在语义/物理泛化，弱在“可验证的状态 + 可逆的恢复 + 接触时域”。本轮不跟它们比“更大的 VLA”，而是比**谓词接口 + 残差调节 + 自适应时域 + 部署/合规**。

### D.2 P0-1：GPR-VLA（主押注）

**动机**：32 个任务不是 32 个独立技能，而是约 16 个谓词/8 个关系的组合；官方人为干扰又会撤销谓词。用“目标谓词 − 当前信念”的残差驱动动作，比“任务 ID + 端到端”更省数据、更可验证、更可恢复。

**与现有方案的差异**：

- 与 WLA/MolmoAct2 的端到端语言条件相比：显式暴露 `z*`、`b`、`r`，动作头知道“差哪个谓词”，而不是只靠隐空间。
- 与 SPA-VLA 相比：部件 token 不只是感知特征，而是谓词信念的观测；动作条件在残差上。
- 与 RPSM 相比：不是外部状态机，而是同一 checkpoint 内的信念头；`b` 可逆，修复由残差自然触发。
- 与 CycleVLA/SPR 相比：不跑第二个 VLM planner；失败检测/恢复蒸馏进同一模型；不用特权状态。

**技术可行性**：高。WLA 已提供 6B G1 底座和 action expert；只需加 part queries、predicate head、goal compiler、residual projection。VLM 可冻结，只训 action expert + 轻量头（官方文档默认单卡 24GB 可微调 action expert）。[S15]

**所需资源**：

- 数据：32 任务约 33k episodes/169h；部件教师标注 10–30 万关键帧；谓词标签由任务元数据 + 时序对齐弱监督；人工验证 1–2k 帧。
- 算力：8×H100 80GB，LoRA/action-expert 1–2 周；推理 1×H100/L40S 先测 1 端口，再按 N 扩展；6B BF16 约 12GB 权重。
- 接口：一个 checkpoint；离线教师不进运行时；`reset()` 清 per-episode belief。

**落地步骤**：

1. 定义 16 谓词 + 8 关系 + 部件短语表；把 32 任务映射成目标谓词序列。
2. 用 SAM3/PartSAM 在关键帧生成 part mask/centroid/3D；质量门控；人工验证。
3. 在 WLA action expert 上加 part queries、predicate head、goal compiler、residual projection；先冻结 VLM。
4. 训练：动作 flow matching + 谓词 BCE + part mask/centroid + 时序一致性 + 语言-谓词对比。
5. 用反向播放/对象移除/状态翻转构造 undo 数据；训练 belief 可逆。
6. 全 32 任务 LPL；与 WLA baseline 消融；再决定是否解冻 VLM。

**风险**：谓词表过粗/过细；语言→谓词解析错误；信念误报导致错误修复；部件分割噪声；单模型审计争议。缓解：谓词表先小后大；低置信回退语言策略；时序平滑/迟滞；oracle 谓词上限实验；manifest 声明。

**验收**：full success 相对 WLA baseline ≥ +1.5pp（目标 +3pp）；undo 恢复成功率 ≥ 50%；未见物品成功率不下降；oracle 谓词上限 ≥ +2pp，否则转 contact servo。

### D.3 P0-2：LPL + Task Portfolio 2.0

**动机**：官方 320 次试验，SE≈2.56pp；1–2pp 的榜单差距是噪声。必须用 Beta-Binomial 后验和边际收益分配调试预算，先消灭 0% 任务。

**差异**：上一轮“高地板/首点优先”改为“最差任务优先 + 组合优化”；步骤分只在成功率不下降时优化。

**可行性**：高。纯统计 + 评测器；不需要新模型。

**资源**：真机/仿真评测时间；10 trials/task；日志。

**步骤**：

```text
for each weekly cycle:
    update Beta posterior from LPL
    flag tasks with P(p_i < 0.05) > 0.5       # no-zero
    for each task:
        gain_i = target_i - E[p_i]
        score_i = gain_i / cost_i             # or UCB_i / cost_i
    allocate debug/training budget to top tasks
    re-run LPL; repeat
```

**风险**：真机成本；验证集过拟合；任务难度先验偏差。缓解：分层抽样、配对场景、bootstrap CI、留出任务。

**验收**：0% 任务清零；E[S] 提升 ≥2pp；Var(S) 不升；预算分配可解释。

### D.4 P0-3：Compliance Compiler 2.0

**动机**：单模型、外部数据/模型、许可证、人机安全、任务硬编码，任何一项不清都可能归零。

**差异**：从 checklist 变成“规则→实现→测试”的运行时门禁；每条规则有代码和测试。

**可行性**：高。工程 + 审计。

**资源**：规则文本、部署、红队；1 人周。

**步骤**：

1. 规则 manifest：单模型、32×10、180s、N 端口、token、reset、交互质量。
2. 静态扫描：不加载第二个 policy；不按任务切权重；不读 task id；不写死坐标。
3. 运行时：模型 hash 不变；per-port session 隔离；watchdog；安全限幅。
4. 提交包：模型卡、数据卡、SPDX/NOTICE、红队报告、复现脚本。
5. 红队：人手接近、超时、NaN、端口断连、内存泄漏。

**风险**：规则未读全；单模型定义争议；外部模型许可证。缓解：保守默认（只用挑战数据 + Apache-2.0 底座）；提交前读 5.1/5.2；manifest 披露。

**验收**：4h soak 无崩溃；安全事件可恢复；单模型 hash 不变；无 task id 依赖。

### D.5 P1-1：AH-TP（自适应时域 + 时长/接触强调）

**动机**：WLA 默认 chunk=30@30fps=1s；自由空间高效，接触/人手太慢。180s 预算需要“还剩多少时间”的决策。

**差异**：不是固定 chunk、不是在线 RL、不是第二个模型；同一 checkpoint 预测 `h_t` 和 `d_k`，用谓词边界/动作一致性/接触距离做离线标签。

**可行性**：中高。已有 DEHP/AAC/GeoAAC 证明自适应 horizon 有效；我们加谓词/截止时间约束，不做在线 RL。[S21][S22][S23]

**资源**：动作一致性标签、真机延迟数据、轻量头；1–2 周。

**步骤**：

1. 离线标签：对每个训练帧，找最长未来前缀，使动作与当前 chunk 的偏差 < 阈值；谓词切换处强制短 horizon。
2. 训练 horizon head（分类/回归）和 duration head（谓词持续时间）。
3. 运行时：`h = min(H, h_t, deadline_steps)`；接触/人手 `h≤2`，自由空间 `h=8–16`。
4. 截止调度：若 `elapsed + d_k > 180s`，选择低成本修复/安全停止。
5. 消融：固定 H vs AH；无 duration vs 有 duration；无接触强调 vs 有。

**风险**：horizon 抖动；与接触伺服冲突；标签噪声。缓解：迟滞、置信度门控、回退固定 H。

**验收**：成功率 +1–2pp；time-to-complete 降低；p99 不升；timeout 率下降。

### D.6 P1-2：部件接触伺服

**动机**：插头/网线/拉链/瓶盖/钥匙/试管的最后几毫米是纯 RGB 端到端的短板。

**差异**：部件 centroid/normal + 腕部近景 + 相对位姿伺服；不是物体级 6D pose。

**可行性**：中高。需要腕部标定/立体；透明/反光有噪声。

**资源**：腕部图像、深度/立体、接触数据；2–3 周。

**步骤**：部件 3D→对齐→小步伺服→接触检测→失败重试；与 GPR-VLA 的 `inserted/aligned` 谓词闭环。

**风险**：深度噪声、遮挡、力控缺失。缓解：多视角、置信度、速度限幅、重试。

**验收**：T10/T26/T19/T14/T12 成功率 +10pp（目标）。

### D.7 P1-3：Endurance Governor 2.0

**动机**：N 端口、4 路视频、6B、长时并发；p99/热/内存直接吃成功率。

**差异**：服务续航 + 语义续航 + 时域续航；共享后端；不切模型。

**可行性**：高。工程。

**资源**：GPU、监控、4h soak；1–2 周。

**步骤**：共享 6B 后端 + N 个轻量端口；动态 batching；CUDA graphs；FP8 视觉/ BF16 动作；token 压缩（双目融合、部件裁剪）；热节流降级；崩溃重启；4h soak。

**风险**：6B 显存、热节流、端口隔离。缓解：N=3 先测；共享后端；降级阶梯；per-session state。

**验收**：p99 < 0.8×chunk；4h 成功率漂移 <5pp；显存增长 <5%；无崩溃。

### D.8 P1-4：Task-Balanced Replay + 梯度手术

**动机**：32 任务多任务训练会负迁移/遗忘；硬任务微调会伤简单任务。

**差异**：全任务 replay + 硬任务上采样 + PCGrad/CAGrad + 最差任务早停；不是顺序微调。

**可行性**：高。训练技巧。

**资源**：训练算力、32 任务验证。

**步骤**：任务分组（pick-place/insertion/folding/sorting/bimanual）；每轮全任务 replay 5–10%；梯度冲突投影；按最差任务早停；语言/谓词 dropout。

**风险**：梯度手术开销；分组偏差。缓解：先小规模消融；只对共享 LoRA 做投影。

**验收**：最差 5 任务平均 +3pp；简单任务不掉；无灾难性遗忘。

### D.9 P2-1：TTS→ASR 指令增广

**动机**：语言复述只有 5 条；评测可能用未见复述/口音/噪声文本。

**差异**：不引入音频输入；只做离线文本增广；TTS 多音色/语速/加噪→ASR→文本变体。

**可行性**：高。工具成熟；已有语音指令噪声注入先例。[S25]

**资源**：5 条复述、TTS/ASR、1 人周。

**步骤**：生成变体→规范化（填充词/同义词→谓词）→训练 goal compiler→留出复述验证。

**风险**：评测是文本，收益可能 0；ASR 错误引入噪声。缓解：只在 P2；用官方复述做留一法；不把 TTS 变体当真实数据。

**验收**：留出复述的谓词解析准确率 +3pp；真实成功率不下降。

### D.10 P2-2：子目标-动作单调对齐

**动机**：谓词标签是弱监督；需要把语言子目标对齐到帧，才能训练 belief。

**差异**：CTC/DTW 对齐，不手工标帧；用任务元数据 + 部件轨迹。

**可行性**：中。任务顺序可能不唯一；需要调参。

**资源**：任务元数据、帧特征；1–2 人周。

**步骤**：子目标序列→DTW/CTC→帧级谓词标签→人工抽检→训练 belief。

**风险**：对齐错误；多解。缓解：只对齐关键谓词；置信度门控；人工验证。

**验收**：谓词标签与人工抽检一致率 ≥85%。

### D.11 P2-3：Rubric/Step-Score Guard

**动机**：步骤分是 tie-breaker；但为步骤分牺牲成功率不划算。

**差异**：先保成功率，再在成功轨迹上优化步骤分；超时前安全退出保留步骤分。

**可行性**：高。规则。

**资源**：info.json、评测日志。

**步骤**：阶段预算→checkpoint 顺序→超时前安全退出→复测。

**风险**：为步骤分牺牲成功率。缓解：硬约束 S 不降；只在 S 持平时优化 Q。

**验收**：S 不降；Q +5；超时率下降。

### D.12 P2-4：Waist/Pivot 安全探针

**动机**：部分任务需要腰部/底座；但激进运动会带来平衡/外参风险。

**差异**：默认静态；按任务小范围探针；不是全局 pivot 策略。

**可行性**：中。需要真机。

**资源**：G1、探针脚本。

**步骤**：静态基线→逐任务探针→安全限幅→按任务配置。

**风险**：平衡/外参/规则。缓解：小范围、低速、watchdog；默认关闭。

**验收**：需要腰部的任务 +5pp；无安全事件。

### D.13 P3-1：World Model / 仿真增广

**动机**：物理泛化/未见任务。

**差异**：视频预测/合成数据；不是主策略。

**可行性**：低中。算力/资产/规则不确定。

**资源**：14B/视频模型、仿真、算力。

**步骤**：离线评估→小规模增广→消融；不阻塞主线。

**风险**：算力、sim2real、规则。缓解：P3；只在有剩余预算时做。

### D.14 修剪清单（明确不做）

- 在线 SAM3/PartSAM 级联：违反单模型精神，延迟高。
- 独立 progress head：谓词信念本身就是进度，且可逆。
- 运行时外部 VLM planner（CycleVLA 式）：第二个模型；要蒸馏进同一 checkpoint。
- 音频输入/语音输出/语音克隆：API 无音频，评分不测。
- 每任务 LoRA/模型合并：32 份权重，审计风险。
- 从零训 6B：数据/算力/时间不划算。
- 完整仿真 RL：样本效率/安全/时间不允许。
- 激进 waist/pivot：成功率优先；默认静态。
- 大规模 3D 生成增广：P3；先把真实数据 + 部件增广做好。

## E. GPR-VLA：架构、训练、推理

### E.1 总览

```text
4 views (head L/R, wrist L/R) + proprio + language
        │
        ▼
VLM backbone (WLA-1.0-Base; frozen or LoRA)
        │
        ├─ K part queries（初版 16）──► part tokens
        │     ├─ existence / affordance
        │     ├─ 2D mask / centroid
        │     ├─ 3D point / normal (stereo or learned)
        │     └─ descriptor (tracking / memory)
        │
        ├─ Goal Compiler (language tokens)
        │     └─ target predicates z* + relations + part descriptors
        │
        ├─ Belief Tracker (part tokens + proprio + memory)
        │     └─ current predicates b, confidence, last-seen
        │
        ▼
Residual r = z* − b
        │
        ▼
Action Expert (flow matching DiT)
        ├─ action chunk a_{t:t+H}
        ├─ validity horizon h_t
        └─ predicate duration d_k / contact emphasis
```

**一个 checkpoint**：backbone、part head、goal compiler、belief tracker、action expert、horizon/duration head 全在同一计算图。离线 SAM3/PartSAM 只生成标签，部署时不加载。

### E.2 谓词/关系词表（建议初版）

**16 谓词**：

| 谓词 | 含义 | 代表任务 |
|---|---|---|
| `grasped(obj, hand)` | 夹爪闭合且对象随动 | 全部抓取 |
| `in_hand(obj, hand)` | 稳定持有（可搬运） | T02/T03/T10… |
| `on(obj, support)` | 放在支撑面上 | T07/T21/T23… |
| `in(obj, container)` | 放入容器 | T03/T09/T17/T18/T28/T29/T31 |
| `stacked(top, bottom)` | 堆叠 | T20/T25/T27 |
| `inserted(plug, socket)` | 插入 | T10/T26/T12 |
| `aligned(part, target)` | 对齐 | T01/T07/T13/T21/T22 |
| `closed(container)` | 闭合 | T09/T17/T31 |
| `open(container)` | 打开 | T14/T17 |
| `zipped(pouch)` | 拉链闭合 | T19 |
| `unlocked(lock)` | 开锁 | T12 |
| `folded(towel)` | 叠好 | T16 |
| `sorted(item, bin)` | 按类别放好 | T04/T06/T15/T24 |
| `hanging(cup, hook)` | 挂上 | T01 |
| `poured(src, dst)` | 倒出/转移 | T14/T32 |
| `removed(item, loc)` | 从原位移除 | T11/T30 |

**8 关系**：`on`、`in`、`left_of`、`right_of`、`front_of`、`behind`、`above`、`aligned_with`。

**为什么是 16+8**：覆盖 32 任务的主要子目标；再细会增加标注/观测难度，再粗无法区分“抓住”与“放好”。先小后大，用 oracle 谓词上限验证。

### E.3 Goal Compiler（语言 → 目标谓词）

- 输入：VLM 的语言 token（不喂 task id）。
- 输出：`z* ∈ {0,1}^K`（或概率）、关系三元组、对象/部件描述子。
- 训练：
  - 任务元数据给出目标谓词序列；5 条官方复述提供语言多样性。
  - 语言 dropout / 复述替换 / 谓词目标 dropout，防止过拟合单一句式。
  - TTS→ASR 变体只做 P2 增广；不改变官方标签。
- 推理：阈值 0.5；低置信时回退“纯语言条件动作”，不切换模型。
- 关键：**不接收 task id**；任务差异只通过语言和目标谓词进入。

### E.4 Part Encoder + Belief Tracker

- K 个共享 part queries（初版 16），cross-attend 到 4 视图 token；输出存在性、affordance、mask、centroid、3D、descriptor。
- 3D：头部双目 + 腕部近景；无深度时用学习头；透明/反光用多视角一致性。
- Belief Tracker：GRU/HMM 平滑；每个谓词一个概率；允许 1→0；迟滞避免单帧抖动。
- 记忆：`descriptor + 3D + last_seen + confidence + TTL`；遮挡时保持 belief，不把“看不见”当“消失”；对象移除时衰减并重扫描。
- 训练标签：离线教师 + 任务元数据 + DTW/CTC 弱对齐；人工抽检。

### E.5 Action Expert

- 输入：part tokens、`b`、`z*`、`r`、语言、proprio、当前子目标 `k`。
- 输出：动作 chunk（joint 或 EE）、`h_t`、`d_k`、`contact_emphasis`。
- 动作表示：建议 **joint**（数据集动作直接、接触稳定）；训练时加 EE 辅助头/前向运动学一致性，部署只用一个 control space。
- 损失：

```text
L = L_action(flow matching)
  + λ_pred * BCE(b, b_label) + BCE(z*, z*_label)
  + λ_part * (mask BCE/Dice + centroid L1 + 3D L1)
  + λ_temp * (belief temporal consistency + part tracking)
  + λ_lang * (language-part/predicate contrastive)
  + λ_h    * (horizon CE/regression)
  + λ_d    * (duration L1)
```

- `L_action` 用底座原有的 flow matching；不改底座动作头结构，只加 cross-attention/条件投影。
- `L_pred` 对低置信帧降权；教师不确定的帧不强制 mask loss。

### E.6 推理循环（伪代码）

```python
def reset():
    belief = init_belief()
    memory = {}
    t = 0

def get_action(obs):
    l = obs["observation.language"]
    z_star = goal_compiler(l)                  # target predicates/relations
    parts = part_encoder(obs.images, obs.proprio)
    b = belief_tracker(parts, memory)          # current beliefs, reversible
    r = z_star - b
    if done(b, z_star):
        return hold_action()
    k = select_subgoal(r, cost)                # lowest-cost undone predicate
    chunk, h, d = action_expert(parts, b, z_star, r, k, obs.proprio)
    h = min(h, deadline_steps(t, d))
    if human_near(obs):
        h = min(h, 2)
        speed_scale = 0.5
    else:
        speed_scale = 1.0
    if unsafe(obs):
        return safe_retreat()
    return chunk[:h] * speed_scale
```

- `human_near`/`unsafe` 用规则式深度/几何/速度检查，不引入第二个学习模型。
- `done` 用谓词信念 + 任务目标；不是固定步数。
- `select_subgoal` 优先修复被撤销的谓词；如果依赖被破坏，回退到最早受影响的谓词。

### E.7 单模型合规

- 一个 checkpoint hash；运行时不 reload、不按任务切权重。
- 所有任务决策由同一计算图产生；辅助头（part/predicate/horizon）都在同一图。
- 不喂 task id；不读任务文件名；不写死坐标/轨迹。
- 离线教师（SAM3/PartSAM）不参与推理；manifest 声明。
- 安全 monitor 规则式；若使用人检测器，明确标注为 safety monitor，不参与任务决策。
- 若规则对“辅助头”有疑问：提交 model card 说明它们是同一 checkpoint 的一部分。

### E.8 消融矩阵

| 实验 | 变量 | 目的 |
|---|---|---|
| A0 | WLA baseline | 基线 |
| A1 | + part head | 部件监督是否有用 |
| A2 | + predicate head | 谓词监督是否有用 |
| A3 | + goal compiler + residual | 目标残差是否提升多任务/恢复 |
| A4 | + belief memory | 遮挡/撤销是否提升 |
| A5 | + AH-TP | 时域是否提升 |
| A6 | + contact servo | 最后几毫米 |
| A7 | oracle predicates | 上限；判断谓词接口是否值得 |
| A8 | 无 task id vs 有 task id | 证明不是靠任务 ID 过拟合 |
| A9 | joint vs EE | 控制空间选择 |

**关键指标**：full success（主）、step score（次）、unseen-object success、human-recovery success、predicate AUC、part centroid error、p99 latency、timeout rate。

**停止条件**：A7（oracle predicates）相对 A0 的 full success 提升 <2pp → 停止扩大谓词接口，转向 contact servo + AH-TP；A4 无提升 → 简化 memory；A5 无提升 → 回退固定 H。

## F. AH-TP：自适应时域与“动作韵律”

### F.1 动机

- WLA 默认 chunk=30@30fps=1s；固定 1 秒对自由空间高效，但接触/人手进入时反应慢。
- 180s 预算下，失败修复需要知道“下一个谓词还要多久”；固定 chunk 不提供这个信息。
- 官方交互质量会记录延迟/动作规律；频繁短 chunk 会增加 p99 抖动，长 chunk 又降低反应。

### F.2 Horizon 标签

对每个训练帧，定义有效 horizon：

```text
h_t = max h ∈ [1, H]  such that
      || a_{t:t+h} - a_{t:t+h}^{pred} || < ε
      and no predicate boundary in (t, t+h]
      and no human/contact event in (t, t+h]
```

- 动作一致性：用当前 chunk 与未来 chunk 的重叠误差。
- 谓词边界：谓词切换处强制 `h≤2`。
- 接触距离：部件 centroid 与目标距离 < 阈值时缩短。
- 人手：训练时用人手 overlay/真实人手数据标注“human near”。
- 无需在线 RL；离线标签 + 监督学习。

### F.3 时长/接触强调

- `d_k`：从 episode 时间戳和谓词切换估计“完成谓词 k 需要多久”；训练 duration head。
- `contact_emphasis`：在接触阶段降低末端速度/增大动作分辨率；可由部件距离/接触概率调制。
- 截止调度：

```text
remaining = 180 - elapsed
if elapsed + d_k > remaining * 0.9:
    choose repair/stop with lowest expected cost
```

### F.4 运行时

- `execute_steps = min(H, h_t, deadline_steps)`。
- 自由空间：`h_t` 可到 8–16；接触：1–2；人手：1–2 + 减速。
- 迟滞：`h_t` 变化需连续 2 帧确认，避免抖动。
- 回退：horizon head 置信度低 → 固定 H=8（保守）。

### F.5 先例与差异

- DEHP：在线 RL 训 horizon predictor，冻结 chunk policy；我们不做在线 RL，用离线标签 + 监督。[S21]
- AAC/GeoAAC：用动作熵/Flow Matching 几何做推理时自适应；我们加谓词边界/截止时间/接触强调。[S22][S23]
- 差异：AH-TP 与 GPR-VLA 共享 belief/part tokens；horizon 不是独立黑盒，而是谓词阶段的一部分；不增加第二个模型。

### F.6 指标与风险

- 指标：成功率、time-to-complete、timeout rate、replans/episode、p99、human-recovery。
- 风险：horizon 抖动、标签噪声、与接触伺服冲突。缓解：迟滞、置信度、固定 H fallback。

## G. Endurance Governor 2.0

### G.1 服务架构

```text
N ports 8765..8765+N-1
   │
   ├─ per-session state (episode, belief, memory; isolated)
   ├─ request queue / deadline batcher
   ├─ one shared model server (GPR-VLA 6B or 4B fallback)
   ├─ watchdog / health / metrics
   └─ safe fallback (hold/retreat/wait; no model switch)
```

- 一个共享后端，N 个轻量会话；每端口独立 `reset()`，belief/memory 不跨端口。
- 动态 batching 以 p99 deadline 为约束；不无限等 batch。
- 预热：启动时 dummy 前向，分配显存/CUDA graph；避免首个 trial 超时。
- 量化：FP8/INT8 视觉 backbone；动作头 BF16；先测精度再上线。
- 缓存：action chunk/part token/visual token；人手/大位移/置信度下降时失效。

### G.2 延迟与 token 预算

- 控制 30Hz（数据集 30fps；WLA target_fps=30）。chunk=30 → 1s；AH-TP 可变。
- 目标：`p99_inference < 0.8 × T_chunk`；固定 H=8 时 `T_chunk≈267ms`（p99 目标 <213ms），H=30 时 `T_chunk≈1s`（p99 目标 <800ms）。
- 4 路 480×640；按 14px patch 粗估单视图约 1.6k visual tokens，4 路约 6.3k/帧；obs_chunk=2 约 12.5k token（粗估，实际取决于底座 tokenizer/分辨率与是否 merge）。6B prefill 仍很重，必须压缩：
  - **双目融合**：左右头部图像 → 一个视觉流 + disparity/深度 token；减少一半头部 token。
  - **部件裁剪**：腕部图像按 part centroid 裁剪高分辨率小块；背景降采样。
  - **part token 压缩**：16 个 part queries 聚合，不保留全部 patch。
  - **obs_chunk 选择**：能 1 帧不 2 帧；用 proprio/光流补。
- 这些是“服务续航”的核心，不是可选项。

### G.3 显存/热/崩溃

- 6B BF16 权重约 12GB；N=3 独立副本约 36GB + activations，80GB 可行、48GB 紧张；N>2 优先共享后端。
- 热：监控 GPU temp/clock；节流时增大 chunk、降低内部图像分辨率、降低 part head 频率；不切模型。
- 崩溃：supervisor + 端口重启；模型服务保持；日志/健康检查；重连后从 belief 继续（若 episode 未结束）。
- 内存：RSS/显存增长 <5%；无泄漏。

### G.4 语义续航

- 每个谓词存 `belief, confidence, last_seen, descriptor, 3D`；TTL/衰减。
- 遮挡：保持 belief；人离开后重检测/重投影；不把“看不见”当“消失”。
- 撤销：belief 1→0；RPSM 修复；只修被破坏的谓词。
- 对象移除：重扫描；找不到则安全停止，不幻觉继续。
- 阶段切换不重置记忆；只重置 episode。

### G.5 4h soak

- N 个并发会话，固定脚本化任务；记录成功率漂移、p99 漂移、显存增长、热节流次数、崩溃/重启。
- 目标：前 25% vs 后 25% 成功率漂移 <5pp；p99 漂移 <20%；显存增长 <5%；零崩溃。
- 能量：GPU 能耗/每次成功（能测则测）；不猜电池化学。

## H. 单模型多任务训练配方

### H.1 数据混合

- 32 任务全量 replay；硬任务上采样（按当前成功率反比，但设上限防止过拟合）。
- 每轮保留 5–10% 简单任务 replay，防止遗忘。
- 语言 dropout/复述替换；谓词目标 dropout（偶尔只给语言，逼模型用语言）。
- 不喂 task id；不按任务分 normalizer（用全局统计，避免任务身份泄漏）。

### H.2 动作空间

- 数据集同时有 joint 和 EE；提交只能选一个。
- 建议 **joint**：接触稳定、数据集动作直接；训练时加 EE 辅助损失/前向运动学一致性，提升空间泛化。
- 若验证显示 EE 更好（位置泛化/底座移动），再切 EE；不混用两个 control space。

### H.3 梯度冲突

- 任务分组：pick-place、insertion、folding、sorting、bimanual、tool-use。
- 共享 LoRA/action expert 上用 PCGrad/CAGrad；只对冲突层做投影，避免全模型开销。
- 早停看最差 5 任务平均，不看总平均；防止“强任务掩盖弱任务”。

### H.4 灾难性遗忘

- 每轮全 32 任务 LPL；记录每任务 Wilson CI。
- 若某任务掉 >10pp，加入 replay/降低学习率；不接受“平均涨、单任务崩”。
- VLM 冻结 + LoRA 优先；全量微调只在最后阶段、且验证不遗忘时。

### H.5 训练阶段

| 阶段 | 目标 | 数据/损失 | 门禁 |
|---|---|---|---|
| S0 | WLA baseline 复现 | 32 任务 action flow matching | 能跑通评测；baseline 成功率 |
| S1 | part/predicate 头 | 部件/谓词标签 + action | 谓词 AUC/部件误差可用 |
| S2 | goal compiler + residual | 语言→谓词 + 残差条件 | 多任务不降；恢复初现 |
| S3 | belief memory + undo | 反向/移除/翻转增广 | undo 恢复 ≥50% |
| S4 | AH-TP | horizon/duration 标签 | 成功率/时延提升 |
| S5 | contact servo | 腕部近景/部件 3D | 硬任务 +10pp |
| S6 | 全 32 任务 | 全量 replay + portfolio | 32×10 正式协议 |

### H.6 算力

- WLA action expert 微调：官方文档默认单卡 24GB 可跑（VLM 冻结）；LoRA 更省。[S15]
- 全量/LoRA VLM：8×H100 80GB，1–2 周；部件教师标注 8 卡 2–4 天（10–30 万帧）。
- 推理：6B BF16 ~12GB；1×H100 先测 1 端口；N=3 共享后端；4B ER-Flow 作为延迟 fallback。

## I. 语音合成：只保留两个间接落点

### I.1 为什么不能做主策略

- 提交 API 观测：4 路图像、proprio、文本语言；**没有音频键**。[S5]
- G1 的 4 麦克风/5W 扬声器/TTS 在机器人本体上；评测是远程 API，模型服务拿不到音频。[S13][S14]
- 语音输出不参与评分；还可能干扰人为干扰协议。**不做。**

### I.2 TTS→ASR 指令增广（P2）

- 取 5 条官方复述；用多音色/多语速/加噪 TTS 合成；ASR 转回文本；得到带识别错误的变体。
- 规范化：填充词、同义词、语序 → 谓词/关系。
- 训练 goal compiler；用留出复述验证。
- 先例：机器人语音理解中的噪声注入/ASR 错误增广可提升语义解析鲁棒性。[S25]
- 预期：0–1pp；只在 P2，不阻塞主线。

### I.3 韵律→动作时域（P1，已并入 AH-TP）

- TTS 的 duration predictor 预测音素时长；动作侧预测谓词持续时间 `d_k`、接触阶段减速/强调、停顿。
- 这不是“语音”，而是“时序生成”的类比；与 AH-TP 共用 head。
- 参考 TTS 时长预测的工程经验（显式时长计划减少幻觉/截断），但机器人侧用离线标签，不用 TTS 模型。[S27]

### I.4 语音安全播报（不评分）

- 可用 G1 TTS 播报“开始移动/请让开/重试”；提升可读性/人机安全，但**不依赖**它影响评分。
- 不把语音作为策略动作；不把语音输出写进 API 返回。

### I.5 修剪

- 音频编码器、语音输入、语音克隆、情感 TTS、语音作为动作。全部不做。

## J. 评测协议与 Task Portfolio

### J.1 LPL 协议

- 每任务 10 trials；5 类泛化各 2（位置/干扰物/背景/未见物品/人为干扰）。
- 离线：留出 episode（每任务 10–20%）；按任务/难度/时长分层。
- 半离线：按官方 `human_1/human_4` 构造扰动；仿真/真机调试。
- 真机：优先 T01/T04/T10/T15/T16/T24/T30；每任务 5–10 trials。
- 统计：每任务 Wilson 95% CI；总体 bootstrap CI；报告 `E[S]`、`P(S>S*)`、`Var(S)`。
- 不挑成功 trial 上报；所有 trial 落日志。

### J.2 Portfolio 算法

```text
p_i ~ Beta(α0 + k_i, β0 + n_i - k_i)
E[S] = (1/32) Σ E[p_i]
Var(S) = (1/32^2) Σ Var(p_i)
P(S > S*) via Monte Carlo

for each cycle:
    flag P(p_i < 0.05) > 0.5          # no-zero
    score_i = (target_i - E[p_i]) / cost_i
    allocate budget to top tasks
    re-run LPL
```

- 先验：Easy `Beta(3,3)`、Medium `Beta(2,4)`、Hard `Beta(1.5,5)`；或统一 `Beta(2,2)`。
- `target_i`：同类任务 75th percentile，或 `min(0.8, E[p_i]+0.2)`。
- `cost_i`：历史调试时长、接触密度、任务时长、失败模式数。
- 高方差任务优先“保守化”（固定 seed/温度 0/更短 chunk/更稳恢复），不追高均值。

### J.3 指标

- 主：full success（每任务/总体）、95% CI。
- 次：step score（tie-break）、checkpoint 完成率、超时率。
- 泛化：5 类分桶成功率。
- 状态：undo detection、repair success、time-to-recover、false alarm。
- 感知：predicate AUC、part mask IoU、centroid error、3D error。
- 部署：p50/p95/p99、jitter、显存、热节流、4h soak 漂移。
- 合规：单模型 hash 不变、无 task id、许可证清单、红队通过。
