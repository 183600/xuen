## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（竞赛策略 → 这不是一场「平均准确率」考试，而是一场「带预算的排名组合赛」）**
直觉：大多数队伍会把 32 个任务当成 32 个独立的准确率目标，追求「平均成功率」。但排行榜是成功率与步骤分的综合排序，且每任务有满分 100 的步骤分——这意味着：(a) **分数是二维的**，成功率和步骤分可能不同权，甚至可能是字典序；(b) **分数是非线性的**，步骤分有里程碑阈值与先后依赖，存在「分数悬崖」；(c) **评测是带噪声的**，N 台机器人、随机顺序、每任务若干次，排名是随机变量的函数；(d) **预算是稀缺的**，工程时间、GPU、真机时段都有限。于是正确的对象不是「把每个任务都提一点」，而是**在 32 个任务 × 多种干预之间做风险调整后的投资组合**：先消灭灾难性零分（保底），再把预算压到「每单位预算边际分数最高」的任务/里程碑上（冲刺），并留出期权价值（保留一次更好的提交机会）。核心反直觉点：**在榜单未公布、且用户上下文称榜首 <30% 的弱场里，最大的敌人不是「不够先进」，而是某个任务上的灾难性零分与方差；先做 min-max，再做 max-mean。**

**灵感 2（决策规划 → VLA 是「动作生成器」，不是「决策者」）**
直觉：现有方案把全部智能压进一个 observation→action chunk 的映射里：它知道「下一步动作像什么」，但不知道「现在该做哪个子目标、什么时候切换、失败后该继续还是恢复、该不该多花计算」。而计分是按里程碑步骤给的——**动作正确 ≠ 决策正确**：在错误时机做一个漂亮的抓取，分数仍然是零。缺的是一层轻量、可解释、毫秒级的**分层决策规划器**：在冻结的 VLA 之上，用选项（option）/子目标/终止条件/恢复策略，把「反应式动作块」变成「目标导向的里程碑推进器」。核心反直觉点：**在不增加模型参数、不违反单模型边界的前提下，一层 5–10ms 的元控制器可能比再训一个更大的动作头更能提分，因为它优化的是「分数」而不是「动作似然」。**

**两者统一**：竞赛策略是**元层**的决策——在任务/实验/提交之间分配预算以最大化排名；决策规划是**回合层**的决策——在选项/里程碑/计算之间分配时间以最大化步骤分。两者共用同一个「分数模型」：`分数 = f(成功率, 步骤分)`，`步骤分 = Σ 里程碑权重 × 达成指示`。第 1–2 轮解决「能力从哪来」（数据引擎），本轮解决「能力如何变成分数」（决策引擎）。本轮结论：**中期边际收益已经从「数据/模型」转向「决策」——但决策层必须建立在已核实的事实与可观测的分数结构上，否则只是把过拟合从模型搬到策略。**

## 2. 对前两轮痛点的增量修订

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2）

> 检索日期：2026-11-26 / 2026-11-27；来源见 §10。承接 v1.1：I1/I2/I5/I8/I9 深化，I10–I12 新增，I7 并入 I12，I3/I4 降为选项组件。清单只增改不重置。

## 0. 本轮主线（一句话）

**前两轮把「能力」做出来；本轮把「能力」变成「分数」：用 I10 决定把预算押到哪，用 I11 决定回合内怎么走，用 I12 决定什么时候多算——三者共用同一张分数模型。**

## 1. 竞赛策略的严谨定义

### 1.1 分数模型

对任务 t∈[32]、回合 e∈[N_t]，令 K_t 为官方得分点（Scoring Steps）数，m_{t,e,k}∈{0,1} 为第 k 个得分点是否达成，w_{t,k} 为权重（Σ_k w_{t,k}=100）。则

  s_{t,e} = Σ_k w_{t,k} m_{t,e,k} ∈ [0,100],
  y_{t,e} = 1[s_{t,e}=100]（或官方定义的全达成）.

任务聚合：
  p_t = (1/N_t) Σ_e y_{t,e},  q_t = (1/N_t) Σ_e s_{t,e}.

榜单综合分（未知，建族）：
  L_θ = θ · (1/32)Σ_t p_t + (1-θ) · (1/32)Σ_t q_t/100,  θ∈[0,1],
或字典序 L = (mean p, mean q)（先比成功率，再比步骤分）。
稳健目标：maximize min_{θ∈Θ} L_θ（或 max CVaR_α(L_θ)），Θ 为根据公开信息与少量真机结果校准的可行权重集。

### 1.2 三个关键量

- **边际分数弹性**：e_t = ∂E[L]/∂u_t，u_t 为对任务 t 的投入（数据量/增广强度/选项先验/评测次数）。组合优化按 e_t / cost_t 排序。
- **分数悬崖（cliff）**：若 m_{t,k}=0 导致后续得分点全不可达，则称 k 为悬崖点。悬崖点下游权重 W_{t,k}=Σ_{j≥k} w_{t,j}；应优先保悬崖点的可靠性，而非平均提高所有点。
- **成功邻近度**：p_t 高且 q_t 接近 100 的任务，边际收益来自「最后一公里」；p_t 低但 q_t 已较高的任务，边际收益来自「部分分」而非全成功。

### 1.3 保底 / 冲刺 / 放弃三分

| 类型 | 判据 | 策略 | 例子（假设，待核实） |
|---|---|---|---|
| 保底 | 当前 p_t 高或 q_t 高，且 cliff 强 | 保守策略 + 恢复选项 + 不折腾 | 已接近满分的简单抓放 |
| 冲刺 | 边际弹性高、成本低、与保底任务冲突小 | 激进增广/选项/多采样 | 差一个里程碑即满分的任务 |
| 放弃 | 边际弹性低、成本高、负迁移风险大 | 只保留最低成本兜底，不投入 | 远任务/极难任务 |

注意：弱场（榜首 <30%）下，保底任务的期望排名贡献通常大于冲刺任务；先做 min-max，再做 max-mean。

## 2. I10 竞赛策略层：分数感知任务组合与风险预算 ★★★★★

- **动机**：排行榜是综合排序（F20），步骤分有里程碑与依赖（F17/F21），评测有方差（F23），预算是稀缺的；均匀投入必然次优。
- **与现有方案差异**：别人按「任务成功率」排优先级；本点按「边际分数/成本」并显式建模目标函数不确定性、悬崖与方差。
- **技术可行性**：高。核心是离线统计 + 少量真机 + 蒙特卡洛影子榜单，不需要新模型。
- **所需资源**：1 人周工程 + 现有评测数据；真机只用于校准 3–5 个任务的 (p,q) 后验。
- **落地步骤**：
  1. 逆向每任务 Scoring Steps（wiki + 挑战页 JS 端点 + 示例视频），建 `score_card.json`：K_t、w_{t,k}、依赖边、悬崖点。
  2. 用离线评测/历史真机结果给每个任务建 (p_t,q_t) 后验（Beta/Normal），并记录不确定性。
  3. 建 `shadow_leaderboard`：对目标函数族 Θ 与对手分数分布做蒙特卡洛，输出当前策略的排名分布、CVaR、保底失败概率。
  4. 用带成本的 Bayesian optimization / 知识梯度分配预算：每轮选「期望排名增益/成本」最高的 (task, intervention)。
  5. 每次真机后更新后验与 Θ；若某任务连续两次低于 LCB，降级为放弃/兜底。
- **风险**：目标函数族设错（缓解：Θ 覆盖字典序与加权两类，且用 min-max；真机校准权重）；步骤分结构误读（缓解：先做小规模真机对照，确认失败/超时是否计分）。

### 2.1 伪代码：组合优化 + 影子榜单

```python
@dataclass
class TaskPosterior:
    p: float; p_var: float          # success rate
    q: float; q_var: float          # step score 0..100
    cliff: float                    # 0..1, downstream weight concentration
    cost: float                     # cost per unit intervention
    transfer: dict[str, float]      # task -> transfer coefficient

def composite(p, q, theta):
    return theta * np.mean(p) + (1 - theta) * np.mean(q) / 100.0

def shadow_rank(my_samples, field_samples, thetas):
    # my_samples/field_samples: (S, 32) arrays of (p,q) draws
    ranks = []
    for th in thetas:
        mine = composite(my_samples[...,0], my_samples[...,1], th)
        field = composite(field_samples[...,0], field_samples[...,1], th)
        ranks.append((field > mine[:,None]).sum(1) + 1)
    return np.array(ranks)          # (len(thetas), S)

def allocate(post, budget, thetas, risk_aversion=1.0):
    x = {t: 0.0 for t in post}
    while budget > 1e-6:
        best, best_score = None, -1e18
        for t, tp in post.items():
            # expected marginal gain, with cliff-weighted variance penalty
            gain = marginal_gain(tp, x[t])
            score = gain / tp.cost - risk_aversion * tp.p_var * (1 + tp.cliff)
            if score > best_score:
                best, best_score = t, score
        x[best] += STEP; budget -= post[best].cost * STEP
    return x
```

（`marginal_gain` 用后验均值 + 离线 L0 弹性估计；真实实现需做交叉验证与敏感性分析。）

## 3. I11 分层决策规划器：里程碑驱动选项元控制器 ★★★★★

- **动机**：VLA 输出动作 chunk，但不决定「做哪个子目标、何时切换、失败怎么办」；计分按里程碑，反应式策略在长程/接触任务上易在错误子目标上耗光时间。
- **与现有方案差异**：不是再加一个大模型，而是在冻结 VLA 上加一层轻量 options/SMDP 元控制器；动作仍由同一 VLA（或合规的脚本选项）产生。
- **技术可行性**：中-高。选项库可先用规则/状态机，Q 头用离线数据回归/IQL；元控制器推理 <5ms，不增加每步延迟。
- **所需资源**：1–2 人周；复用 32k 示教 + I5 合成恢复段；无需额外真机训练。
- **落地步骤**：
  1. 定义选项库 O（见 3.1）与每个选项的 initiation/termination/cost。
  2. 用得分点检测器（I5）给示教打里程碑标签，切出选项段；训练 `progress_head` 与 `option_q_head`。
  3. 先跑规则版元控制器（if-else + 进度阈值）做 L0 回放；再加 Q 头做切换/恢复。
  4. 在 3 个弱任务（PlugCharger / ZipUp / PourOutMedicine）上做 L0 反事实与单任务通道 A/B。
  5. 接入 I4 的 `yield`、I3 的 `servo`、I5 的 `recover`，统一由元控制器调度。
- **风险**：选项抽象过粗/过细（缓解：先用官方得分点对齐，一个得分点一个选项；粒度由 L0 消融定）；Q 头分布外（缓解：规则兜底 + 保守切换阈值）；脚本选项触碰单模型边界（缓解：优先「同一 VLA + 子指令提示」实现选项，脚本仅 I3' 备案）。

### 3.1 选项库（与得分点对齐）

| 选项 | 进入条件 | 终止条件 | 低层实现 | 对应得分点示例 |
|---|---|---|---|---|
| approach | 目标可见、距离远 | 进入抓取位姿邻域 | VLA 子指令 / 关键点伺服 | 接近物体 |
| grasp | 夹爪开、物体在抓取区 | 夹爪闭合且物体随动 | VLA chunk | 抓取成功 |
| lift | 已抓取 | 物体离桌 > h | VLA chunk | 提起 |
| move | 已抓取/已提起 | 到达目标邻域 | VLA chunk | 搬运 |
| insert/align | 接近目标 | 插入深度/对齐误差达标 | 关键点伺服 + VLA | 插入/对齐 |
| press/pour | 已对齐 | 触发/倾倒完成 | VLA chunk | 按压/倾倒 |
| place/release | 到位 | 物体稳定、夹爪开 | VLA chunk | 放置 |
| reapproach | 进度停滞/置信低 | 重新进入 approach | VLA + 规则 | 恢复 |
| yield | 检测到人手 | 人手离开 + 稳定 | 停持/让位 | 安全（不计分但保命） |
| abort | 不可恢复/时间不足 | episode 结束 | 规则 | 止损 |

### 3.2 伪代码：元控制器

```python
OPTIONS = ["approach","grasp","lift","move","insert","press","pour","place",
           "reapproach","yield","abort"]

class OptionMetaController:
    def reset(self, obs):
        self.belief = self.progress_head.init(obs)   # milestone posterior
        self.option = None
        self.t = 0
        self.stall = 0

    def act(self, obs):
        b = self.progress_head(obs, self.belief)
        if self.option is None or self.option.done(obs, b) or self.stall > STALL_MAX:
            o = self.select(obs, b)
            self.option = self.option_lib[o]
            self.stall = 0
        a = self.option.act(obs)                     # VLA chunk / servo
        self.stall = 0 if self.progress_gain(b) > EPS else self.stall + 1
        return a

    def select(self, obs, b):
        if human_detected(obs):                      # safety overrides value
            return self.option_lib["yield"]
        if time_left(obs) < self.option_lib["abort"].min_time:
            return self.option_lib["abort"]
        q = {o: self.q_head(obs, b, o) for o in OPTIONS}
        q["reapproach"] += RECOVERY_BONUS * self.stall
        return max(q, key=q.get)
```

### 3.3 Q 头训练（弱监督 + 离线 RL）

- **输入**：VLA 视觉嵌入（池化）、proprio、`progress_head` 的里程碑后验 b、当前选项 one-hot、已用时间。
- **回报**：`r_t = Δ(步骤分) + λ·Δ(成功指示) - c·Δt`；用示教轨迹的蒙特卡洛回报做回归；用 IQL/CQL 处理分布外。
- **标签来源**：官方得分点检测器（I5）+ 示教成功段；失败/恢复段由 I5 合成。
- **保守性**：只在 Q 优势 > margin 时切换；否则保持当前选项，避免抖动。

## 4. I12 预算感知测试时计算调度 ★★★

- **动机**：不同决策时刻的价值不同；在接近悬崖/接触/高不确定时多算，在搬运/低风险时少算；同时要稳定 p99（F22 的准计分轴）。
- **与现有方案差异**：I7 只在「高险节点做世界模型 rollout」；本点把它纳入统一的「计算的价值」框架，并显式建模 chunk 级预算与延迟波动。
- **技术可行性**：中。需要先测清评测端的调用间隔（chunk 是否整段执行）；调度器本身是轻量规则/树模型。
- **所需资源**：1 人周；复用 I7 的世界模型资产（若保留）。
- **落地步骤**：
  1. 用本地 `example_env` + 日志测 `get_action` 调用间隔，确认 `B_c = T_a/f - ε` 的实际值。
  2. 实现不确定性估计（动作方差 / 多采样分歧 / 进度头熵）。
  3. 实现四档计算 `d∈{0,1,2,3}` 与延迟画像；用 token bucket 管理预算。
  4. 在 L0 回放中比较「固定 d=1」vs「风险自适应 d」的步骤分/延迟；只在 p99 不退化时上真机。
- **风险**：评测端实际逐帧调用导致预算远小于假设（缓解：在线测间隔，自动退化为保守模式）；多采样/世界模型的动作分布异常触发可信度问题（缓解：动作健康度过滤 + 只在选项边界使用 d≥2）。

### 4.1 时间模型

设控制频率 f=15Hz，chunk 长度 T_a，评测端整段执行 chunk，则两次 `get_action` 之间约有

  B_c ≈ T_a / f - ε

的墙钟预算。T_a=8 → ≈533ms；T_a=16 → ≈1067ms。若评测端逐帧调用，则 B_c≈66ms。两种模式都要支持：

| 档 | 计算 | 典型延迟 | 使用条件 |
|---|---|---|---|
| d=0 | 复用缓存 chunk | <2ms | 低风险、预算紧 |
| d=1 | 单次 VLA 前向 | 30–40ms | 默认 |
| d=2 | best-of-k 采样 + 选择 | 60–120ms | 高不确定、chunk 预算充足 |
| d=3 | 世界模型短 rollout / 重规划 | 150–400ms | 悬崖点、选项边界、有预算结余 |

### 4.2 伪代码：计算的价值

```python
def choose_compute(obs, belief, budget):
    risk = uncertainty(obs) * stakes(belief) * (1 + cliff_factor(belief))
    best_d, best_voc = 1, -1e18
    for d in [0, 1, 2, 3]:
        gain = expected_gain(d, risk)          # 离线校准的剂量-响应
        lat  = latency_profile[d]
        if lat > budget.remaining:             # 硬预算
            continue
        voc = gain - LAMBDA * lat - MU * latency_var(d)
        if voc > best_voc:
            best_d, best_voc = d, voc
    budget.spend(latency_profile[best_d])
    return best_d
```

## 6. 实验设计（决策层 + 组合层）

### 6.1 分级验证

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0-a | 分数模型敏感性：Θ 网格下 I10 推荐排序是否稳定 | 离线（免费） | top-5 任务集合在 Θ 上 Jaccard > 0.6 |
| L0-b | 选项元控制器反事实回放：固定 VLA，比较规则版 vs Q 头 vs 无元控制器 | 离线（免费） | 步骤分 Δ>0 且无任务退步；切换次数/抖动可控 |
| L0-c | 计算调度：固定 d=1 vs 风险自适应 d | 离线 + 本地 stub | 步骤分不降、p99 不升 |
| L1 | 2^(k-p) 析因：元控制器 on/off × 恢复 on/off × 增广轴 on/off | 少量真机 | 主效应显著 ≤3 个组合进 L2 |
| L2 | top 组合真机确认：≥2 任务 × 各 2 次 | 单任务通道 | 真机增益 ≥ 离线预测的 50%；p99 < 40ms（或 chunk 预算内） |
| 门禁 | PR4 + F22：run_client 全流程、延迟抖动、动作健康度 | 本地 stub | 0 拒绝动作、无异常离群、延迟稳定 |

### 6.2 实验组合按 VoI 分配

定义实验 x 的价值：

  VoI(x) = E[决策改进 | x] - cost(x)
         ≈ Σ_{决策 d} P(x 改变 d 的选择) × |Δ期望排名(d)|

优先做能改变「保底/冲刺/放弃」分类或「元控制器是否上线」的实验；不做只影响小数点后第三位的实验。每个真机时段前，先算一次 VoI 排序，把预算给最高 VoI 的实验。

### 6.3 影子榜单与方差缩减

- 用目标函数族 Θ + 对手分数先验（弱场：对手分数低方差大）做蒙特卡洛，输出：当前策略的排名分布、P(掉出前 k)、CVaR。
- 真机评测采用「固定 canary 任务 + 配对比较」：同一 canary 任务在每次提交中重复，作为控制变量，估计评测漂移。
- 报告均值的同时报告 LCB；提交决策用 LCB 而非均值，避免「一次好运」误导。
