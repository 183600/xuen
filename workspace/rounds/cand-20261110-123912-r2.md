# 第 44 轮（新循环第 4 轮） · Delay-Cert × Provenance-Cert：把「通信延迟」与「开源生态」纳入分布式可验证证书闭环（四层架构 v9）

> 承接第 43 轮 v20（Persona-Cert × Concurrent-Cert）。v20 把「用户」和「并发」纳入证书闭环，但它仍压着两个隐含的单点假设：**(H1) 所有证书与测量都在同一节点、同一时钟、同一瞬时完成**——租约新鲜度判据 m−λ(t−τ)≥θ 默认 τ 与 t 共享时钟，且测量结果无需跨网络传输；**(H2) 证书产出栈是封闭可信的**——VLM 权重、CBF 库、监控器二进制、调度器都被默认为「我们自己的代码」。真实系统恰恰相反：边缘-云-多机之间证书要**跨网络传输**，推理栈由**大量第三方开源组件**拼接。本轮灵感词「通信延迟」「开源生态」精确命中这两个假设：**通信延迟**迫使我们把「年龄」从本地时间差升级为「传输延迟 + 时钟偏斜 + 排队抖动」的区间上界，并发现证书边际在悲观融合下构成一个**抗乱序/抗分区的 meet-半格**——分布式安全由此不再需要共识；**开源生态**迫使我们把「证书」从一条结论升级为**携带溯源的工件**（工件哈希 + 依赖 Merkle 根 + checker 哈希 + 构建溯源 + 签名），并把「依赖变更」变成可计算的**再认证影响闭包**。二者耦合处是本轮真正的新问题：一个溯源完美、但由**被投毒的 checker** 产出、又经过**被延迟放大的陈旧测量**的证书，会在所有审计都通过的情况下静默不 sound。

## 0. 直觉与动机

**灵感 1（通信延迟 → 安全用半格、可用性用新鲜度，两件事必须分开）**：分布式系统里最危险的幻觉是「我收到了一个很乐观的边际」。远端说 m=0.9，但这条消息已在队列里躺了 200ms，机器人不能把它当此刻的 0.9。正确做法**不是**让所有节点对时、对同一张证书达成共识（那会被 FLP 与延迟拖垮），而是让**安全**只依赖一个单调运算：`m_used = min_src (m_src − λ_src·A_src)`。取 min 的妙处是——乱序、重复不改变结果；而**任一是需求源缺失或过期，融合结果直接降为 ⊥（阻塞/降级）而不是被省略**，于是丢失绝不会让结果变乐观。**安全不需要共识，只需要「宁小勿大 + 缺证即停」**；共识/新鲜度只影响**可用性**（多少证书还活着、何时能离开 ⊥）。这把 v20 的本地租约升级成一个**分布式单调结构**。

**灵感 2（通信延迟的正面：有界延迟可被「前向补偿 + 本地续租」吃掉）**：若延迟有硬上界 δ_max，则不必把整段延迟都算作不确定增长：可用有界动力学把源端测量前向传播，且在收到后用**本地新鲜观测续租**（把 t_r 刷新为本地时刻、δ_max 归零）。于是延迟惩罚只剩「从源端测量到本地首次收到」这一不可约段，而非此后整个使用期。这把「延迟」从纯负担变成**可摊销成本**；但代价是 δ_max/ε_clk 必须是真上界，否则补偿本身就在放大错误。

**灵感 3（开源生态 → 证书自带出生证明 + 依赖变更的增量再认证）**：开源栈里任何一次传递依赖小版本升级、一次被投毒权重、一次 CI 被劫持，都可能让「证书」变成对错误二进制签的字。因此证书必须绑定：**工件哈希**（部署的到底是哪份权重/二进制）、**依赖闭包 Merkle 根**（SBOM）、**checker 哈希**（哪个验证器、哪个版本产出的）、**构建溯源**（可复现构建 / SLSA）与**签名**。推论是**依赖条件化 soundness**：只要部署工件与证书绑定哈希一致、且 checker 对任意同哈希工件 sound，则 claim 成立；一旦哈希不符（替换/升级/投毒），证书**自动失效**而非静默错误——开源生态的「可替换性」被转成**失败即收缩**，而不是失败即不安全。进一步的杠杆是**再认证影响闭包**：依赖是 DAG，某节点变更后只重认证它的祖先证书，而非全量重跑。

**灵感 4（开源生态的正面与陷阱：异构冗余 vs 共同因失效）**：开源生态天然提供多个独立实现，可做 N 版本冗余校验（不同 CBF 库、不同 checker、不同运行时），这是对抗「单一 checker 有 bug」的真杠杆。但陷阱是**相关性**：若多数实现都依赖同一个上游基础库/同一份校准数据/同一个 CI 根，则 N-of-M 只是虚假的独立。因此「独立性」必须用**依赖闭包不相交 / 不同 checker 家族**来定义，而不是简单计数。

**灵感 5（耦合 → 联合信任根：延迟上界与 checker 可信度是同一类假设）**：延迟 soundness 依赖 δ_max 与 ε_clk 是**真上界**；checker soundness 依赖 checker 哈希与签名链**真的未被污染**。二者看似无关，实则是同一类承诺：**我们对一个运行时无法观测其内部的「外部根」（网络最坏时延 / 验证器二进制）作了乐观假设**。本轮因此把信任显式建模为两类根证书：**网络确定性证书**（TSN/时间感知整形等可强制的最坏时延）与**验证器根证书**（可复现构建 + 多方独立复现的 checker）。任一被推翻，整个联邦证书网都可能「审计全过但结论错了」。

**架构升级**：DCF（延迟感知证书联邦）把 v20 的本地租约表升级为跨节点悲观融合网络；PBC（溯源绑定证书）把每条 claim 升级为携带 provenance 的可验证工件；ERE（生态再认证引擎）把依赖变更变成增量失效传播。四层架构由此从 v8 的「人格 + 并发」升级为 v9 的「人格 + 并发 + 分布式延迟 + 供应链溯源」。

## 1. 形式化定义（增量：定义 44–49）

**定义 44（延迟感知证书租约与年龄窗）**：证书租约 ℓ=(m, t_s, t_r, δ_max, λ, max_age, κ, src)：m 为源端测得边际下界，t_s 为源端测量时刻（源时钟），t_r 为本地接收时刻，δ_max 为可强制单向最坏传输延迟上界，λ 为衰减率，max_age 为最大可接受年龄，κ 为关键级，src 为源节点。设时钟偏斜上界 ε_clk。定义**可用年龄上界** A(t_use) = (t_use − t_r) + δ_max + ε_clk。**新鲜度判据**改为 m − λ·A(t_use) ≥ θ。**命题（延迟感知 sound 性）**：若 (i) 真实单向延迟 ≤ δ_max，(ii) 两节点时钟偏斜 ≤ ε_clk，(iii) 状态位移满足 ||x(t_use) − x(t_s)|| ≤ v_max·(t_use − t_s)，且 (iv) A(t_use) ≥ t_use − t_s，则用该租约守卫绝不误用陈旧边际，即 m_true(t_use) ≥ m − λ·A ≥ θ。**推论**：分区或延迟违反 δ_max 时，租约必须按过期处理——延迟失效检测器与租约绑定，而不是可选监控。

**定义 45（需求集上的悲观融合 meet-半格）**：任务由 v20 的 rely-guarantee 接口静态声明其安全守卫所需的证书源**需求集** Req(t)。融合状态取值于偏序 {⊥} ∪ ℝ，⊥ 表示缺证/过期/分区/未就绪（禁止使用），且 ⊥ ⊑ m 对所有 m。收到源 src∈Req 的租约 ℓ 后，候选下界 b_ℓ = m_ℓ − λ_ℓ·A_ℓ(t_use)。**融合** m_used = min_{src∈Req} b_ℓ(src)，且**仅当每个 src∈Req 都存在未过期租约时才允许离开 ⊥**。**命题**：(i) 对已接收的 sound 下界，融合满足交换律、结合律、幂等律（乱序/重复不改变结果）；(ii) 任一需求源缺失或过期时结果为 ⊥ 而非被删除，故**消息丢失绝不会使 m_used 变乐观**；(iii) 增加一个新需求源的证据只会使 m_used 单调不增。**定理（无共识分布式 sound 性）**：若所有离开 ⊥ 的融合值都由 Req 中每个源在年龄窗内的 sound 租约构成，则对任意投递顺序、重复、丢失与任意分区，一旦允许使用，m_used 都是真实边际的 sound 下界。**意义**：分布式**安全**无需共识，共识/心跳只决定「何时能离开 ⊥」，即只影响**可用性**。

**定义 46（溯源绑定证书 PBC）**：证书 c=(φ, h_art, r_dep, χ, π_build, σ)：φ 为 claim（如「守卫 e 在域 D 上 m_lo≥θ」），h_art 为工件（权重/二进制/配置）哈希，r_dep 为依赖闭包 SBOM 的 Merkle 根，χ 为 checker（验证器）的工件哈希与版本，π_build 为构建溯源（可复现构建哈希 / SLSA 证明），σ 为签名。**验证谓词** V(c)：σ 有效 ∧ h_art 与部署工件一致 ∧ r_dep 与部署依赖闭包一致 ∧ checker 注册表中 χ 被判定 sound ∧ π_build 可被独立复现。**依赖条件化引理**：若 V(c) 成立且 checker χ 的可靠性成立，则 φ 对部署系统成立；若运行时再校验发现 h_art 或 r_dep 不符，则 c 无效（fail-safe 收缩），绝不「证据不足地放行」。**注**：这把开源生态的「依赖可替换」转成「替换即失效」，soundness 归约到哈希抗碰撞与 checker 根可信。

**定义 47（再认证影响闭包）**：依赖 DAG G=(V,E)，u→v 表示 u 依赖 v。工件 w 变更后的**影响闭包** I(w)={ c : closure(c) ∩ {w} ≠ ∅ }，其中 closure(c) 由 (h_art, r_dep, χ) 引用的节点集合给出。**再认证集** R(w)=I(w)。**定理（增量再认证 sound 性）**：若变更前证书集 Σ 全 sound，变更后对所有 c∈R(w) 重新验证、且对所有 c∉R(w) 有 closure(c) 不含 w，则 Σ' 仍全 sound。**代价**：全量重认证 O(|Σ|)，增量仅 O(|I(w)|)，成熟生态中后者期望远小于前者。**接口级补充**：若变更只改实现不改 rely-guarantee 接口（定义 40），可在接口兼容下豁免部分重认证；若改接口（读写集/阈值），必须升级到契约层并检查组合性——开源生态的 semver 并不保证接口语义。

**定义 48（生态信任与 N-of-M 独立复现）**：工件 a 的生态信任 ρ(a) 由独立、溯源验证的复现计数与签名背书构成；但**晋升闸门不做纯声誉**：把 a 从「候选」晋升为「可入证书」需 N 个**相互独立**的复现者对同一 h_art 复现出相同结论（M 中取 N），且每个复现自身 V 验证通过。**独立性**定义：两个复现者的依赖闭包不相交或分属不同 checker 家族（防共同因失效）。**引理（声誉不可单独解锁扩张）**：τ_u（v20 信任预算）与 ρ(a) 只能用于**收缩轨道的排序**，绝不允许绕过 N-of-M 闸门去扩张安全域；未知/低信任工件默认取最坏情形（等价于收缩到不可用），符合「收缩免费、扩张持证」。

**定义 49（开放证书互操作与组合 OCI-C）**：统一证书交换格式 OCI-C=(φ, provenance 摘要, rely/guarantee 接口签名, 版本约束, σ)。来自不同厂商的证书 c1,c2 可组合当且仅当：rely-guarantee 接口兼容（G_1⇒R_2 ∧ G_2⇒R_1，定义 40）、provenance 的依赖闭包不冲突、版本约束可满足。**组合定理**：若 c1,c2 各自 sound 且上述接口兼容成立，则组合系统保持联合不变式 I_1 ∧ I_2；若不兼容则必须显式协商/降级，不得默认拼接。**推论**：开源生态的互操作必须建立在「可机械检查的接口契约」上，否则组合即引入未证明的信任假设。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-60 DELAY-AWARE CERT FABRIC（延迟感知证书联邦 DCF）
1. **延迟感知租约表**：每条租约携带 (m, t_s, t_r, δ_max, λ, max_age, κ, src)；年龄用 A=(t_use−t_r)+δ_max+ε_clk，而非本地时间差。
2. **需求集悲观融合**：按 rely-guarantee 接口静态声明 Req；缺证/过期即 ⊥；融合为 min，天然抗乱序/重复/丢失，安全无需共识。
3. **本地续租与前向补偿**：收到后用本地新鲜观测刷新 t_r、δ_max 归零；有界动力学前向传播源端测量，摊销不可约传输段。
4. **延迟失效检测**：心跳/分区检测与租约绑定，违反 δ_max 立即失效；HI 模式下优先保监控租约（复用 v20 混合关键级）。

### 2.2 IP-61 PROVENANCE-BOUND CERT（溯源绑定证书 PBC）
1. **证书工件化**：claim 绑定 h_art / r_dep / χ / π_build / σ，证书即「出生证明 + 结论」。
2. **依赖条件化验证**：V(c) 全通过才可用；任何工件/依赖/checker 不符即自动失效（fail-safe 收缩）。
3. **SBOM 与可复现构建**：Merkle 化依赖闭包；构建溯源可被第三方独立复现；签名链绑定发布者。
4. **checker 根注册表**：把「验证器本身可信」显式化为一等根证书，checker 变更触发全局再认证。

### 2.3 IP-62 ECOSYSTEM RE-CERTIFICATION ENGINE（生态再认证引擎 ERE）
1. **影响闭包计算**：反向依赖可达 + closure(c) 命中判定，得到最小再认证集 R(w)。
2. **增量失效传播**：仅重认证 R(w)，其余证书保持；接口级变更额外走契约组合检查。
3. **N-of-M 独立晋升**：按依赖闭包不相交/不同 checker 家族选独立复现，满足 N 才晋升。
4. **互操作与组合审计**：OCI-C 解析、接口兼容检查、跨厂商组合不变式验证。

## 2. 关键算法（伪代码）

### IP-60 DCF：延迟感知融合、本地续租与分区失效
```
BOTTOM = None
def fuse_margins(req, leases, t_use, eps_clk):
    best = {}
    for src in req:                          # 静态需求集：缺一不可
        l = leases.get(src)
        if l is None: return BOTTOM          # 缺证 -> 阻塞/降级，绝不省略
        A = (t_use - l.t_r) + l.delta_max + eps_clk
        if A > l.max_age: return BOTTOM      # 过期/分区 -> 失效
        best[src] = l.m - l.lam * A
    return min(best.values())                # meet：只降不升

def delay_aware_guard(req, leases, theta, t_use):
    m = fuse_margins(req, leases, t_use, EPS_CLK)
    return (m is not BOTTOM) and (m >= theta)

def local_refresh(remote_lease, x_local, t_local):
    # 用本地新鲜观测续租：延迟只惩罚不可本地刷新的那一段
    b = cert_lookup_L0(x_local)
    return Lease(m=min(remote_lease.m, b.m_lo),
                 t_s=remote_lease.t_s, t_r=t_local,
                 delta_max=0,                 # 已本地化，传输项归零
                 lam=remote_lease.lam, max_age=remote_lease.max_age,
                 kappa=remote_lease.kappa, src=remote_lease.src)

def forward_compensate(lease, t_use):
    # 有界动力学前向传播：用 v_max/L_m 把源端测量推进到使用时刻
    A = (t_use - lease.t_r) + lease.delta_max + EPS_CLK
    return lease.m - lease.lam * A            # 与 age 窗一致，等价保守补偿
```

            and cert.h_art == hash(deployed.artifact)

### IP-62 ERE：影响闭包、增量再认证与独立晋升
```
def impact_closure(dep_dag, changed):
    return union(ancestors(dep_dag, w) for w in changed)   # 反向可达

def incremental_recert(dep_dag, changed, certs, deployed):
    R = [c for c in certs if closure(c) & set(changed)]
    revoked = []
    for c in R:                                 # 只重认证影响闭包
        if not verify_provenance(c, deployed(c)):
            revoked.append(c)
    return R, revoked                           # 非全量重跑

def n_of_m_promote(artifact, reproductions, N):
    indep = select_independent(reproductions)   # 依赖闭包不相交 / 不同 checker 家族
    agree = [r for r in indep
             if r.result == reproduce(artifact, r.checker)]
    return (len(agree) >= N
            and all(verify_provenance(r.cert, deployed(artifact)) for r in agree))

def compose_certs(c1, c2):
    if not (c1.G.implies(c2.R) and c2.G.implies(c1.R)):  # rely-guarantee 兼容
        return Negotiate("interface-mismatch")
    if dep_closures_conflict(c1.r_dep, c2.r_dep):
        return Negotiate("dependency-conflict")
    if not version_constraints_satisfiable(c1, c2):
        return Negotiate("version-conflict")
    return CombinedCert(I=c1.I & c2.I)          # 联合不变式
```
