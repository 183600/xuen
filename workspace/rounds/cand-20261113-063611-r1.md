# 灵感循环 v3 · 第 3 轮迭代（「伦理与合规」×「动作分块」）—— 动作块是一份有期限、可审计、可回退的承诺

> 承接 v2（Gazebo × 实时性 × 模块化设计，UIP-01′~15）。本轮先做一次**接口级纠错**，再用两个新词重排清单。最重要的新证据来自评测端代码而非官网文案：`example/example_env.py` 对每个动作键做 `shape != (action_chunk_size, *per_frame)` 的硬校验（README §3 亦明确 "Each action array has shape `(T_a, …)`"）。这意味着 **v2 的 UIP-13「每次可返回 ≤k 步的块」在官方评测器上不成立**：`T_a` 在握手时冻结，运行期每次必须返回恰好 `T_a` 步。动作分块因而不是"运行期旋钮"，而是**一次性承诺**；运行期唯一能做的是**块内内容编排**与**块边界核验**。
>
> 第二个新证据来自公开数据集的 `meta/info.json`：32 个数据集共 **33,276 episodes / 18,282,246 帧**；平均 episode **6.2–37.6 s**，按"平均 episode 时长 / 计分步数"粗估，**单个计分步的自然时长中位数约 5.7 s（≈171 帧 @30 Hz）**。也就是说，一个安全的动作块（数十步）通常只覆盖一个计分步的**一小段**。这迫使验证从"计分步级"下沉到"子目标 / 接触事件级"。

## 1. 直觉：动作块是"盲承诺"

想象你对评测器说："接下来 8 步请照做，我不看。"这句话有三个伦理后果：

1. **不可撤回**：这 8 步里如果人把手伸进来，机器人不会停；它只会把已经排好的动作做完。
2. **不可解释**：如果这 8 步导致坏事，你必须能说清楚是哪个模型、哪份输入、哪个配置、哪次验证导致的——否则无法复盘。
3. **不可推卸**：如果这 8 步里有不可逆动作（插入、释放、倒出、合盖、拉链），后果已经发生在物理世界里，不能靠"下一块再改"抹掉。

所以动作分块不只是控制频率问题，它把"承诺"具体化了。伦理与合规在这个接口里不是外加的审稿意见，而是**承诺的边界条件**：承诺要短到能被人打断，要可回退，要能解释，要按风险定价。

直觉上最反常识的一点是：**不可逆动作应该尽量前置，而不是后置**。因为"动作做在错误状态上"（安全后果）通常比"动作被别人撤回"（分数后果）更严重；把不可逆动作放在刚观测完、状态最新鲜的块首，能最大化它作用在正确状态上的概率。后置只对"分数优先"有利。这个结论在 §4 有严格推导。

## 2. 严谨定义：承诺合同

**定义 1（动作块 / 承诺）**。第 `τ` 次调用 `get_action(o_τ)` 返回
`A_τ = (a_{τ,1}, …, a_{τ,T_a})`，评测器按索引顺序执行，期间不再观测。称 `A_τ` 是一次长度为 `T_a` 的**承诺**；它把"接下来 `T_a` 个控制拍的世界演化"交给了策略。

**定义 2（可采纳承诺）**。`A_τ` 可采纳，当且仅当同时满足：

- **接口**：`A_τ` 每个键的 shape 恰为 `(T_a, *per_frame)`、dtype 正确、只含声明键、`meta.token` 正确。
- **闭包**：`A_τ = f_θ(o_τ, h_τ; κ)`，其中 `f_θ` 是声明过的单模型，`h_τ` 是该端口的隔离历史，`κ` 是握手配置；运行期不调用外部 oracle / 网络 / 未声明模型。
- **安全**：对 `A_τ` 的每个前缀，护栏谓词 `G(·, o_τ)=1`（关节/速度/力矩/工作空间/人机距离/自碰撞）。
- **审慎**：`CVaR_α[H(A_τ; ξ)] ≤ B`，`ξ` 取自扰动场景生成器（DRF）。
- **可验证**：一个块最多**新完成一个**计分检查点；检查点完成后的剩余步只能是**可逆填充**，不得开始下一个检查点的不可逆动作。
- **可审计**：把 `(o_τ, A_τ, 模型哈希, 配置哈希, 风险, 验证结果)` 追加到只追加账本。

**定义 3（风险定价）**。对扰动场景 `ξ`，定义块内加权伤害

`H(A; ξ) = Σ_{i=1}^{T_a} γ^{i-1} · ℓ(s_i, a_i; ξ)`，

其中 `ℓ = w_h·1[人进入安全包络] + w_i·irreversibility(a_i) + w_f·force_i² + w_s·1[掉落/泼洒/尖锐物失控]`。用 Rockafellar–Uryasev 的 CVaR：

`CVaR_α(H) = min_η { η + (1/(1-α))·E[(H-η)^+] }`。

取 `α=0.9`，因为不可逆伤害是尾事件，期望值不足以表达"审慎"。

**定义 4（伦理优先序）**。在可采纳集 `F` 上做字典序优化：
**物理安全（硬） ≻ 规则合规（硬） ≻ 任务成功/步骤分（软） ≻ 延迟/抖动（软）**。
即：绝不拿安全换分；在安全且合规的块里再最大化期望得分；同分时优先低 CVaR、高可回退性。

## 3. 两个灵感词怎么读

### 3.1 动作分块：固定网格上的三种自由

`T_a` 冻结后，运行期只剩三种自由：

1. **选 `T_a` 本身**（握手一次，对全部 32 任务冻结）——这是**一次性全局决策**，对应 UIP-17 OGC。v2 的"按阶段动态选 k"不可实现，必须修正。
2. **排块内动作**（同一组动作的不同顺序/前缀/填充）——对应 UIP-18 PAC 与 UIP-19 RAC。
3. **选块尾状态**（准静态、可恢复、低力）——对应 UIP-19 的块尾准静态约束。

不能做的三件事：运行期改 `T_a`、提前重观测、返回短块。任何声称"自适应块长"的方案，必须先过 `example_env.py` 这一关。

### 3.2 伦理与合规：六层，不是一个"单模型"复选框

1. **规则合规**：接口、token、shape、dtype、`control_space` 互斥、只声明必要 obs 键。
2. **评测诚信**：不靠注入噪声骗"动作规律性"检查、不靠冻结/重复动作骗步骤分、不泄漏测试集、不把仿真结论冒充真机结论。
3. **物理安全**：力/速度/力矩/工作空间/自碰撞/人机距离/尖锐物。
4. **人的主体性**：场景里的人不是"对抗扰动源"，而是有权威的操作者；检测到人介入应**让权**（停/退/等），而不是继续按原计划用力。
5. **可审计**：决策账本、模型/配置哈希、可复现回放、失败也记录。
6. **数据伦理**：数据集许可、隐私、合成数据必须标注、不得把仿真扰动说成真人数据。

这六层最终都落在同一个对象上：**块**。块是承诺，也是唯一能同时被安全盾、审计账本和评测器看见的东西。

## 4. 关键推导（结论先行，证明见产物区）

设任务 `i` 的 episode 长 `L_i`、人为干扰率 `λ_i`（每控制拍）、每次干扰的重做代价 `d_i`、每次调用开销 `c`（以控制拍当量计，含延迟/抖动），则一次 episode 的近似代价

`C_i(T) = λ_i L_i (d_i + T/2) + c L_i / T`。

- **命题 1（全局承诺时域）**：单任务最优 `T_i* = sqrt(2c/λ_i)`；在任务分布 `p_i` 下，握手唯一能选的全局最优 `T_a* = sqrt(2c / λ̄_L)`，其中 `λ̄_L = Σ p_i λ_i L_i / Σ p_i L_i` 是 episode 长度加权的平均干扰率。直觉：干扰越频繁、调用越便宜，块就该越短。
- **命题 2（冻结的代价）**：全局 `T_a*` 相对"每任务各选 `T_i*`"的 regret 为 `R = Σ p_i [C_i(T_a*) − C_i(T_i*)]`。冻结不是免费的，但对高干扰任务的绝对影响最大，对低干扰任务相对影响最大。
- **命题 3（不可逆动作前置）**：若干扰是速率 `λ` 的泊松过程，且"动作做在错误状态上"的安全代价 `H_bad` 大于"动作被撤回"的分数代价 `H_undo`，则把不可逆动作放在块内位置 `a` 的期望代价满足 `dC/da = λ e^{-λa}(H_bad − H_undo) > 0`，故最优 `a=0`：**越早越好**；反之（分数优先）才后置。伦理优先序取前者。
- **命题 4（检查点相位）**：固定 `T_a` 时，一个时长为 `k` 的计分检查点在块内的完成偏移近似均匀，块末之前平均还有 `(T_a−1)/2` 步。若不用 PAC，这些步可能已经开始下一个检查点的不可逆动作；一旦人在这段窗口撤回，机器人就在**错误状态**上继续。PAC 把这些步替换成可逆填充，把"未验证的不可逆推进"降为 0，代价是每检查点约 `(T_a−1)/2` 步的时间。
- **命题 5（人的可打断上界）**：设控制周期 `Δt`、末端最大速度 `v_max`、所需人机间距 `d_safe`、人的反应时间 `τ_h`，则必须
  `v_max·(T_a·Δt + τ_h) ≤ d_safe` ⇒ `T_a ≤ (d_safe/v_max − τ_h)/Δt`。
  这是**安全硬上界**，可能与延迟最优冲突；伦理优先序要求取 `min`。

真实数据给出的尺度感：单计分步中位数 ≈5.7 s ≈171 帧 @30 Hz，而一个安全块通常只有几拍到几十拍。因此**一个块几乎从不完成一个完整计分步**——验证器必须识别"抓稳了 / 对准了 / 插入到深度 D / 盖子合上了"这类**子目标事件**，而不是等官方计分步。

## 5. 上轮诊断与 v3 重排

- **必须纠错**：v2 UIP-13 的"返回 ≤k 步"假设与评测器冲突。升级为 **UIP-17 OGC**：握手期一次性选 `T_a`，并把延迟/抖动预算（原 UIP-15）并入目标函数。运行期的"自适应"改由 **UIP-18 PAC**（块内相位）与 **UIP-19 RAC**（块内动作语法）实现。
- **升级**：UIP-01′/02′ → UIP-01″/02″，验证与计分网下沉到"子目标事件级"，并只在块边界运行；UIP-09′ → **UIP-20 HAD**，从"检测撤回→重做"升级为"检测人介入→让权→恢复"；UIP-12 DRF 增加"人介入时序/力度/意图"场景，供 CVaR 与 HAD 使用。
- **新增**：**UIP-16 CARE**（旗舰，承诺合同架构）、**UIP-17 OGC**、**UIP-18 PAC**、**UIP-19 RAC**、**UIP-20 HAD**、**UIP-21 EGS**（伦理护栏盾）、**UIP-22 CAL**（合规审计账本）。
- **降级/边缘化**：UIP-05 LCAG 保留为语言条件化支撑；UIP-08′ LAT-ENG、UIP-14 MSGR 保留为工程支撑，但必须服从 UIP-22 的闭包审计（所有模块在声明的单模型图内，不能有"影子模型"）。
- **封存不变**：UIP-04、UIP-10 继续封存。

**v3 的一句话主张**：不要再问"块长调到多少最好"，先问"这 `T_a` 步里，哪些动作是不可逆的、在什么状态下执行、被人打断会怎样、事后能不能证明"。

## 6. 瓶颈假设（更新）

- **H1（接口）**：`T_a` 冻结 + 整块盲执行 ⇒ 运行期真正的杠杆是**块内动作语法**，不是块长；谁先把"可逆填充 / 不可逆前置 / 块尾准静态"做成默认，谁就能在不违反接口的前提下拿到恢复性与安全性。
- **H2（时标）**：计分步时标（≈5.7 s）远大于安全块时标（≈0.1–1 s）⇒ 官方计分点太粗，不能直接当验证器；**子目标/接触事件级验证器**是必需品，且必须能从公开数据弱标注。
- **H3（伦理）**：人介入应被当作**权威信号**而非噪声；"让权"会在短期内损失吞吐，但在撤回型干扰下减少"在错误状态上继续用力"，从而同时降低安全风险和重做代价。
- **H4（合规）**：可信度指标（延迟波动、动作规律性）本质上是**评测诚信**的一部分；用噪声/抖动掩盖问题会适得其反，稳定、可解释、可复现的块更安全。
- **H5（审计）**：单模型合规无法靠口头保证；需要**闭包测试 + 哈希账本 + 回放复现**三件套，否则一旦被质疑，成绩不可辩护。

---

## 7. 本轮最大风险 & 押注

**一句话**：把"伦理/合规"当成架构正确性的证明，而真正的红线（单模型口径、时限、控制频率、`T_a` 是否允许变长、人工干扰是否计入正式分）仍锁在未取到的手册里——一旦 `T_a` 被证实可逐次变化或允许短块，OGC/PAC 的相当一部分设计需要重写。

**→ 本轮最值得押注**：**UIP-16 CARE 的"块内动作语法"（UIP-18 PAC × UIP-19 RAC × UIP-21 EGS）**。它不依赖仿真保真度、不依赖额外模型、完全落在 `T_a` 固定与单模型闭包之内，却直接对准"反向撤回 + 人机安全 + 可信度"三个真实约束；OGC 负责握手期选一个不后悔的期限，HAD 负责把"人"从扰动源还原成权威，CAL 负责让所有结论可辩护。

## 2. 符号与形式定义

| 符号 | 含义 |
|---|---|
| `T_a` | 握手时冻结的动作块长度（控制拍数） |
| `Δt` | 控制周期（若按数据集 30 fps，则 ≈1/30 s） |
| `A_τ=(a_{τ,1..T_a})` | 第 τ 次承诺的动作块 |
| `o_τ` | 第 τ 次调用的观测 |
| `f_θ` | 声明过的单模型；`θ` 为其参数 |
| `h_τ` | 该端口隔离的历史/KV 状态 |
| `κ` | 握手配置（控制空间、obs 键、缩放、`T_a`、token） |
| `G(·)` | 确定性护栏谓词 |
| `ξ` | 扰动场景（DRF 采样） |
| `H(A;ξ)` | 块内加权伤害 |
| `CVaR_α` | 尾风险（α=0.9） |
| `g_j` | 第 j 个官方计分检查点；`s_j` 为其分值 |
| `k_j` | 完成 `g_j` 所需的控制拍数 |
| `k̄` | 单计分步的自然时标（数据统计≈171 帧 @30 Hz） |
| `c` | 每次调用的开销（控制拍当量，含延迟/抖动） |
| `λ` | 人为干扰率（每控制拍） |
| `d` | 一次干扰造成的重做代价（控制拍当量） |
| `ρ(a,s)` | 动作 a 在状态 s 的可逆度 ∈[0,1] |

### 定义 1（承诺 / Commitment）
`A_τ = f_θ(o_τ, h_τ; κ)`，评测器按 `1..T_a` 顺序执行，期间不重观测。称 `A_τ` 为一次长度 `T_a` 的承诺。

### 定义 2（可采纳承诺 / Admissible）
`A_τ` 可采纳 iff：

1. **接口**：每个动作键 `shape=(T_a,*per_frame)`、`float32`、只含声明键、`meta.token` 正确、索引 0 先执行。
2. **闭包**：`A_τ` 完全由 `(f_θ, o_τ, h_τ, κ)` 决定；运行期无外部网络/oracle/未声明模型。
3. **安全**：`G(A_τ, o_τ)=1`（逐前缀）。
4. **审慎**：`CVaR_α[H(A_τ;ξ)] ≤ B`。
5. **可验证/相位**：一个块最多新完成一个计分检查点；检查点完成后的剩余步只能是可逆填充。
6. **可审计**：账本追加 `(obs_digest, action_digest, model_hash, config_hash, risk, verifier_state, mode)`。

### 定义 3（风险定价 / Risk price）
`H(A;ξ)=Σ_{i=1}^{T_a} γ^{i-1} ℓ(s_i,a_i;ξ)`，
`ℓ = w_h·1[人进入安全包络] + w_i·(1−ρ(a_i,s_i)) + w_f·force_i² + w_s·1[掉落/泼洒/尖锐物失控]`。
`CVaR_α(H)=min_η{η+(1−α)^{-1}E[(H−η)^+]}`。取 α=0.9：不可逆伤害是尾事件，期望值不够"审慎"。

### 定义 4（伦理优先序）
在可采纳集 `F` 上字典序优化：**安全（硬）≻ 合规（硬）≻ 成功/步骤分（软）≻ 延迟/抖动（软）**。绝不拿安全换分；同分时优先低 CVaR、高可回退性。

### 定义 5（可逆度阶梯）
| 级别 | 例子 | 可逆性 |
|---|---|---|
| L0 | 自由空间移动、预抓取位 | 高（ρ≈1） |
| L1 | 合爪/张爪 | 高（开爪即撤销） |
| L2 | 抬起/搬运 | 中（可放回） |
| L3 | 接触/对准/轻压 | 中高（可退回） |
| L4 | 插入/拉链/合盖/拧动 | 低（需反向操作） |
| L5 | 释放/倒出/掉落/泼洒 | 极低（任务内不可逆） |

RAC 的目标不是违反任务偏序，而是**把 L4/L5 压缩到"刚观测完"的块首**，把 L0–L3 放到块尾作填充。

## 3. 命题与证明

### 命题 1（全局承诺时域）
近似代价 `C_i(T)=λ_i L_i(d_i+T/2)+cL_i/T`。
单任务最优 `T_i*=sqrt(2c/λ_i)`；任务分布 `p_i` 下全局最优

`T_a* = sqrt(2c / λ̄_L)`，`λ̄_L = Σ p_i λ_i L_i / Σ p_i L_i`。

**证明**：`dC_i/dT=λ_iL_i/2−cL_i/T²=0 ⇒ T²=2c/λ_i`；`d²C_i/dT²=2cL_i/T³>0`，唯一极小。全局：`C(T)=const+(T/2)Σp_iλ_iL_i+(c/T)Σp_iL_i`，求导得 `T²=2c·Σp_iL_i/Σp_iλ_iL_i`。∎

**直觉**：干扰越频繁（λ 大）、调用越便宜（c 小），承诺越短。`T_a` 必须取整数并在握手时定死。

### 命题 2（冻结的 regret）
相对"每任务各选 `T_i*`"，全局 `T_a*` 的 regret 为

`R = Σ_i p_i [C_i(T_a*)−C_i(T_i*)] ≥ 0`。

数值见 §13 表 E：在高干扰任务上绝对影响最大，在低干扰任务上相对影响最大（≈23%）。

### 命题 3（不可逆动作前置）
设人干扰为速率 λ 的泊松过程，不可逆动作在块内位置 `a∈[0,T_a]`，`H_bad`=动作做在被人改过的错误状态上的安全代价，`H_undo`=动作被人撤回的分数代价（简化：忽略同一干扰同时触发两类后果的复合情形）。则

`C(a)=(1−e^{−λa})H_bad + e^{−λa}(1−e^{−λ(T_a−a)})H_undo`，

`dC/da = λ e^{−λa}(H_bad − H_undo)`。

**证明**：令 `A=e^{−λa}`，`B=e^{−λ(T_a−a)}`，`AB=e^{−λT_a}` 为常数。
`C=H_bad−A H_bad + A H_undo − AB H_undo`，
`dC/da=λA H_bad − λA H_undo = λA(H_bad−H_undo)`。∎

**推论**：若 `H_bad>H_undo`（安全优先），`C` 随 `a` 单调增，最优 `a=0`（**前置**）；若 `H_bad<H_undo`（分数优先），最优 `a=T_a`（**后置**）。均匀扰动是 λ→0 的极限，结论相同。伦理优先序取前者。

**工程含义**：可逆的接近/对准应放在**前一个块**完成；包含 L4/L5 的"提交块"应把不可逆动作放在**块首**，块尾用撤退/松开/回中位等可逆动作填充。

### 命题 4（检查点相位与未验证推进）
固定 `T_a` 时，检查点完成时刻在块内的偏移近似均匀，故从完成到下一个块边界的期望步数为 `(T_a−1)/2`。若不用 PAC，这些步可能被用于下一个检查点的 L4/L5，形成**未验证的不可逆推进** `U`。PAC 把 `U` 降为 0，代价是同样步数的可逆填充。

数值见 §13 表 G：`m` 个检查点的总过冲 `≈ m(T_a−1)/2`；`T_a=8,m=3` 约 10.5 步，`T_a=16,m=3` 约 22.5 步。

### 命题 5（人的可打断上界）
设末端最大速度 `v_max`、所需人机间距 `d_safe`、人的反应时间 `τ_h`、控制周期 `Δt`：

`v_max·(T_a·Δt + τ_h) ≤ d_safe` ⇒ `T_a ≤ (d_safe/v_max − τ_h)/Δt`。

这是**安全硬上界**。伦理优先序要求 `T_a ≤ min(T_lat*, T_safe, T_max)`。数值见 §13 表 H：该上界对 `v_max`/`d_safe` 极敏感，手册未公开前只能参数化。

### 命题 6（可复现性）
若 `f_θ` 在一个 episode 内是确定性的，且观测、模型哈希、配置哈希、随机种子均被记录，则用同一模型哈希回放同一观测序列得到的动作摘要必然一致。因此 **CAL 的回放测试是单模型闭包的可操作判据**（不是充分证明，但是强证据）。

## 4. 旗舰深潜：UIP-16 CARE（Commitment-Aware, Risk-priced, Ethical chunking）

CARE 不是又一个模型，而是一层**承诺编译器**：它把"单模型输出的一段动作"编译成一份可采纳承诺。六层结构：

| 层 | 名称 | 作用 | 对应条目 |
|---|---|---|---|
| C0 | 合同层 | 定义 `T_a`、active prefix、风险、provenance | UIP-16 |
| C1 | 风险层 | CVaR 定价 + 硬预算 B | UIP-16/21 |
| C2 | 相位层 | 一块最多一个检查点；剩余可逆填充 | UIP-18 |
| C3 | 动作语法层 | 不可逆前置、可逆填充、块尾准静态 | UIP-19 |
| C4 | 人的层 | 检测人介入→让权→恢复 | UIP-20 |
| C5 | 证据层 | 护栏 + 审计账本 + 回放 | UIP-21/22 |

### 4.1 CARE 主循环（伪代码）

```python
class CARE_Policy:
    def __init__(self, backbone, verifier, guardrail, drf, cfg):
        self.f   = backbone          # 唯一声明的模型
        self.V   = verifier          # 几何/规则 或 同骨干小头（禁止外部 VLM）
        self.G   = guardrail         # 确定性安全谓词
        self.DRF = drf               # 扰动场景采样器
        self.Ta  = int(cfg.Ta)       # 握手冻结
        self.mode = "NORMAL"         # NORMAL | YIELD | RECOVER
        self.g   = 0                 # 当前计分检查点
        self.hist = []               # 该端口隔离历史
        self.skill = SkillGraph(cfg.skill_graph)
        self.ledger = AuditLedger(cfg.model_hash, cfg.config_hash)

    def reset(self):
        self.f.reset(); self.hist.clear()
        self.mode = "NORMAL"; self.g = 0

    def get_action(self, obs):
        # (1) 块边界核验：子目标事件级 done / regressed / human
        ev = self.V.update(obs, self.g)
        if ev.human_present or ev.human_contact:
            self.mode = "YIELD"
        elif ev.regressed:
            self.mode = "RECOVER"
        elif ev.done:
            self.g += 1; self.mode = "NORMAL"

        # (2) 按模式生成"候选块"
        if self.mode == "YIELD":
            A = self.yield_chunk(obs)          # 让权：保持/后退，低力、可逆
        elif self.mode == "RECOVER":
            A = self.recover_chunk(obs)        # 从新观测重做被撤回的子目标
        else:
            plan = self.f.plan(obs, self.skill.node(self.g))  # 带可逆度标注的原语
            A = self.construct_chunk(plan, obs)               # PAC + RAC

        # (3) 硬安全 + 审慎预算（字典序）
        if not self.G.safe(A, obs):
            A = self.G.project_or_hold(A, obs)
        # (4) 精确形状：必须是 (Ta, *per_frame)
        A = self.G.pad_exact(A, self.Ta, obs)  # 可逆填充/合规保持，不是零动作
        # (5) 审计
        self.ledger.append(obs, A, self.mode, self.g,
                           self.G.risk_cvar(A, obs, self.DRF))
        return A

    def construct_chunk(self, plan, obs):
        # 一个块最多完成一个检查点
        k = min(self.Ta, plan.steps_to_next_checkpoint)
        # 任务偏序内，把 L4/L5 尽量前置；L0-L3 作填充
        core = plan.order_by_irreversibility(k)
        fill = plan.reversible_fill(self.Ta - k)
        return stack(core, fill)
```

**关键点**：
- `pad_exact` 不是补零，而是补**合规保持/可逆动作**；补零会触发"动作统计异常"的可信度风险，也可能在 `joint` 空间造成突变。
- `yield_chunk` 与 `recover_chunk` 也必须是恰好 `T_a` 步，不能返回短块。
- 所有分支都走同一个 `f_θ` 或确定性规则；`V`/`G` 不允许调用外部模型。

## 5. UIP-17 OGC：固定 `T_a` 下的一次性承诺时域

### 直觉
`T_a` 就像"每次闭眼走几步"。闭眼越久，越省调用，但撞上人的概率越大；闭眼越短，越安全，但来回次数多、延迟抖动大。因为评测器只让你在握手时说一次"闭眼几步"，你只能选一个对 32 个任务都不太后悔的值。

### 机制
1. 用公开数据统计每个任务的 episode 长度 `L_i` 与计分步数 `m_i`，得到 `k̄_i`（§13 表 B）。
2. 用 §13 表 C 的公式在"每 episode 一次干扰"假设下估 `T_lat* = sqrt(2cL)`。
3. 用命题 5 估 `T_safe`。
4. 取 `T_a = max(1, round(min(T_lat*, T_safe, T_max)))`（`T_max` 为工程上限：评测时限/延迟预算/显存），并做敏感性分析。
5. 运行期不再改 `T_a`；用 PAC/RAC 在块内恢复"按任务/阶段"的适应性。

### 与 v2 UIP-13 的差异
| | v2 ACS | v3 OGC |
|---|---|---|
| 块长 | 声称运行期按阶段选 `k` | 握手一次，全局冻结 |
| 依据 | 阶段/预算 | 任务混合 + 延迟 + 安全上界 |
| 运行期适应 | 改块长 | 只改块内内容（PAC/RAC） |
| 合规性 | 与 `example_env.py` 冲突 | 严格满足 `(T_a,*)` |

### 风险
`c`、`λ`、`T_safe` 都只能估；若手册给出控制频率/时限/人机间距，必须重算。若实际允许逐次变长，OGC 退化为一个特例。

## 6. UIP-18 PAC：相位对齐分块（单检查点不变量）

### 直觉
固定网格下你没法"把观测点挪到检查点之后"，但你可以**决定检查点之后到块末这几步做什么**：是继续冲下一个不可逆动作，还是先做可逆的撤退/对准/预抓取。后者在被人打断时不会把世界推向更糟的状态。

### 定义（PAC 可采纳）
一个块是 PAC 可采纳的，若：
1. 它最多新完成一个官方计分检查点；
2. 若检查点在块内第 `k<T_a` 步完成，则第 `k+1..T_a` 步全部是可逆动作（L0–L3），不得含 L4/L5；
3. 若一个检查点跨多个块完成，块边界必须落在准静态/可恢复状态，且不得在未验证前启动下一个检查点的 L4/L5。

### 机制
```python
def construct_pac(plan, Ta, g):
    k = plan.steps_to_complete(g)          # 预测
    if k >= Ta:
        return plan.first(Ta)              # 本块不完成检查点，正常推进
    core = plan.commit_prefix(g, k)        # 完成 g 的不可逆前缀（RAC 排序）
    fill = plan.reversible_fill(Ta - k)    # 撤退/对准下一个目标/预抓取
    return stack(core, fill)
```

### 代价与收益
- **代价**：每个检查点平均 `(T_a−1)/2` 步的填充；`T_a=8,m=3` 约 10.5 步/episode（见 §13 表 G）。
- **收益**：块边界最多只有一个"新完成但未验证"的检查点，redo 粒度精确；不会在被人撤回的状态上启动下一个 L4/L5。
- **与 UIP-02″ 的关系**：SSG 提供检查点顺序与分值；PAC 提供"一块一个"的节流。

### 风险
填充动作若被评测器视为"动作规律性异常"（例如长时间不动），会伤可信度；因此填充必须是**有意义的可逆动作**（撤退、重对齐、预抓取），而不是死等。

## 7. UIP-19 RAC：可逆动作分块（不可逆前置 + 可逆填充 + 准静态块尾）

### 直觉
把不可逆动作想成"签字"：你希望在一份刚核对过、最新鲜的文件上签字，而不是在闭眼走了一段之后再签。签完之后的动作应该是可撤销的（收笔、后退），而不是立刻再签一份。

### 机制
1. **可逆度标注**：对模型输出的动作原语标注 `ρ∈[0,1]`（可用规则：释放/倒出/插入/合盖→低；接近/对准/抬升→高）。
2. **偏序内前置**：在任务偏序允许的范围内，把 L4/L5 放到块首；L0–L3 放块尾。
3. **提交块分段**：可逆接近放在前一个块；含 L4/L5 的块从"刚观测完"开始，先提交，再填充。
4. **块尾准静态**：块末的末端速度低于 `v_ε`、物体有支撑、夹爪状态稳定；否则用最后几步做"settle"。
5. **与 PAC 合流**：提交块同时满足"一块最多一个检查点"。

### 命题 3 的直接应用
安全优先（`H_bad>H_undo`）⇒ 不可逆动作前置。若某任务确实"分数优先"（例如失败也无物理风险），可把 `H_bad/H_undo` 作为配置项翻转，但默认安全优先。

### 风险
前置可能增加"动作做在尚未完全对准的状态上"的风险；因此前置的前提是**块首观测足够新、护栏确认对准**。RAC 不是盲目前置，而是"在状态最新鲜时提交"。

## 8. UIP-20 HAD：人类让权（Detect–Defer–Recover）

### 直觉
场景里的人不是"扰动函数"，而是有意图的操作者。机器人不应该和人的手"抢"物体；正确反应是：停、退、等，等人完成后再从新状态重规划。把人当对手，既不安全，也常常更丢分。

### 模式机
```
NORMAL --(人进入安全包络/接触)--> YIELD
YIELD  --(人离开且场景稳定 τ_wait)--> RECOVER
RECOVER --(被撤回的子目标重做完成)--> NORMAL
NORMAL --(检测到非人因 regressed)--> RECOVER
```

- **YIELD**：输出低力、可逆的保持/后退块；不追目标；不做 L4/L5；记录人介入前后的状态差。
- **RECOVER**：从**新观测**重规划，而不是从旧计划继续；若子目标被撤回，重做该子目标（RHPV-D 的 `regressed` 分支）。
- **NORMAL**：正常 CARE 循环。

### 与 v2 UIP-09′ 的差异
| | v2 DCR-R | v3 HAD |
|---|---|---|
| 人的角色 | 扰动源 | 权威操作者 |
| 反应 | 检测撤回→重做 | 检测→让权→等待→恢复 |
| 安全 | 未显式 | 硬约束（不与人争力） |
| 数据 | 反向撤回演示 | 人介入时序/力度/意图场景 |

### 风险
让权会损失吞吐；若"人"是恶意持续阻挡，可能永远无法完成。为此设**有界耐心**：等待 `τ_max` 后，若还有可独立完成的子目标则先做（在任务偏序允许时），否则安全保持并记录。

## 9. UIP-21 EGS：伦理护栏盾

### 直觉
评测器会**整块盲执行**，所以安全不能等到执行后再说；必须在提交前用确定性规则把危险动作挡住。护栏不是"又一个模型"，而是一组可审计的硬约束。

### 约束（逐前缀检查）
```python
def safe(A, obs, cfg):
    for a in A:
        if not (cfg.q_min <= a.q <= cfg.q_max):        return False
        if abs(a.qdot) > cfg.v_max:                    return False
        if abs(a.tau)  > cfg.tau_max:                  return False
        if not in_workspace(a.ee, cfg.W_safe):         return False
        if dist(a.ee, obs.human_cloud) < cfg.d_min:    return False
        if self_collision(a):                          return False
        if sharp_object_unsupported(a, obs):           return False
    return True
```

### 投影/替换
- 优先把关节目标 `clamp` 到安全集；
- 若仍不安全，替换为**合规保持块**：关节目标=当前观测关节，夹爪=当前开度，`pivot`=当前值；仍返回恰好 `T_a` 步。
- 记录每次替换的原因，供 CAL 审计。

### 与单模型合规
护栏是**确定性规则**，不引入新参数/新模型；其阈值写在配置里并进入 `config_hash`。这既满足单模型闭包，又让安全边界可审计。

### 风险
阈值过保守会显著丢分（例如 `d_min` 太大导致无法接近物体）；阈值过松则失去意义。必须用 GSO/真机锚点校准，并在 CAL 中记录每次触发。

## 10. UIP-22 CAL：合规审计账本

### 直觉
"我们只用了单模型"这句话，评委不会只凭口头相信。你需要能拿出**可重放的证据**：同一观测、同一模型哈希、同一配置，必须产生同一动作摘要；每个块的风险、护栏、验证、模式都要有记录。

### 账本记录
```json
{"ep": 17, "t": 42, "obs": "sha256:...", "model": "sha256:...",
 "cfg": "sha256:...", "Ta": 8, "act": "sha256:...", "mode": "NORMAL",
 "g": 2, "risk_cvar": 0.07, "guard": "ok", "ver": "done",
 "lat_ms": 31.2, "prev": "sha256:..."}
```

- **哈希链**：`h_n = SHA256(h_{n-1} || canonical(record_n))`，只追加。
- **回放**：用同一 `model`/`cfg` 哈希重跑记录的观测序列，比较 `act` 摘要；不一致即闭包/确定性被破坏。
- **合规 linter**（提交前）：
  1. `metadata` 类型/取值/`T_a≥1`/`control_space` 互斥；
  2. 动作 shape 严格 `(T_a,*per_frame)`、`float32`、只含声明键；
  3. 断网运行仍可用；静态扫描无外部 API/未声明模型；
  4. 32 任务各抽 1 episode 回放，`act` 摘要一致；
  5. 数据集许可/哈希/合成数据标注齐全；
  6. 结果报告区分 sim/real，给出置信区间与失败案例；
  7. 反作弊：无动作噪声注入、无冻结刷分、无 token 侧信道；
  8. 每端口 `reset()` 清空历史/KV，状态隔离。
- **诚实报告**：所有真机结论提测前标注 **GSO 代理（UIP-11）**；仿真结果不得写成真机结果。

### 与"单模型"的关系
CAL 不能证明"只有一个模型"，但能提供三类强证据：**闭包（断网可跑）、确定性（回放一致）、数据/配置可追溯**。这比口头声明更可辩护，也能在赛后复现实验中自证。

## 11. 支撑项如何被 CARE 调用

- **UIP-01″ RHPV-D（验证内核）**：只在块边界运行；输入 `(o_τ, g, 子目标事件)`；输出 `done/ongoing/regressed/human`。优先几何/规则判据（抓取闭合、物体高度、插入深度、盖角、拉链位置），零额外模型；需要学习时用**同骨干小头**（满足闭包）。
- **UIP-02″ SSG（计分网）**：提供 32 任务的检查点顺序/分值（v2 §2 表）；PAC 保证"一块最多推进一个检查点"；末步分值 ≥ 前序 ⇒ 保前置、搏末步。
- **UIP-11 GSO（离线神谕）**：不仅给步骤分，还给**安全/可逆性**指标（是否掉落、是否越界、是否与人碰撞、块尾速度）；用于校准 EGS 阈值与 RAC 排序。
- **UIP-12″ DRF（数据工厂）**：生成三类场景：① 反向撤回（v2 已有）；② 人介入时序/力度/意图（新增，供 CVaR 与 HAD）；③ 人持续阻挡/拿走物体（新增，供"有界耐心"测试）。
- **UIP-14 MSGR（技能图）**：32 任务→约 10 个技能节点；每个节点带"子目标事件序列 + 可逆度标注"；所有技能头共享骨干，全部在 CAL 的声明图内。
- **UIP-08′ LAT-ENG（工程）**：多端口隔离、批处理、减少 obs 堆叠/缩放；`T_a` 越小调用越多，需与 OGC 联调；延迟方差进入 OGC 的 `c`。
- **UIP-05 LCAG（语言）**：用 `observation.language` 条件化，处理未见物品/背景；边缘保留，不与 CARE 争夺主叙事。

## 16. 本轮最大风险 & 押注

**一句话**：最大的风险不是算法不够新，而是**把"合规"当成免检章**——真正的红线（`T_a` 是否可变、控制频率/时限、单模型口径、人机安全阈值）仍锁在未取到的手册里，任何一项与假设不符，OGC/PAC/RAC 的参数与收益都要重算。
