# 第 65 轮（承接第 64 轮「GRIP 接触接地四层闭环」IP-204~213；灵感循环 III 第 1 轮；本轮灵感：「角色一致性」×「自然语言指令」）

> 第 64 轮用接触力觉把几何先验变成"可证伪、可接地"，其自述的最大风险是力觉自身成为新的单点故障。但它仍有一个从未被触碰的隐藏假设：**目标本身已经是解析好的形式化 goal，指令的语义角色早已正确绑定**。真实人机协作的输入是自然语言——「把红色积木放到蓝色积木右边」「用锤子敲钉子」「把它递给客人」——它欠定、含指代/省略/否定/量词辖域/角色歧义。此时最危险的已不是"几何幻觉"，而是**角色滑移（role slip）与角色坍缩（role collapse）**：机器人安全、稳定、可认证地做错了事——因为它把"递给客人"的主客体或工具/目标绑反了。物理安全证书救不了语义错误。于是本轮的核心命题是：
>
> **把鲁棒性从「几何/接触可证伪」升级为「语义可接地、角色可核验、歧义可主动澄清」——自然语言不是命令字符串，而是带角色框架的欠定意图；角色一致性是把指令语义接进认证闭环的可检验不变量。**

## 0. 直觉与动机

**灵感 1（自然语言指令 → 角色框架：语言是带槽位的压缩意图）**
直觉：人不会给机器人下发 AST。一句话是"谓词 + 若干语义角色 + 约束"的压缩：施事 agent、受事 patient、主题 theme、工具 instrument、目标 goal、起点 source、接受者 recipient、方位 location、方式 manner，以及否定 ¬、量词 ∀/∃、时序 ≺、条件 → 等约束。危险不在词错，而在**同一表层形式可对应多个角色结构**：「红色积木右边的蓝色积木」谁是 referent、谁是 anchor；「用锤子敲钉子」谁是 instrument、谁是 patient；「把杯子给客人」谁给谁。把指令解析成**角色框架 F = (p, ρ, C)** 并给出角色-实体绑定分布，是接地的第一步。

**灵感 2（角色一致性 → 可核验不变量）**
直觉：人执行任务时角色是"锁定"的：你说"把杯子递给客人"，杯子不能中途变成被递的人。角色一致性至少有四个可检验面：(i) **时序保持**：计划相邻步骤中持久角色绑定同一实体身份；(ii) **指代保持**：代词/省略必须回指同一实体，不得随上下文漂移；(iii) **角色单射**：不同角色不能静默绑到同一实体（除非语言显式允许，如"自己递给自己"）；(iv) **改写不变**：同一指令的改写（主动/被动、同义替换、语序调整）诱导的角色绑定应一致。**把这些做成裕度 ρ_role，"语义接地"第一次能像几何那样被认证。**

**灵感 3（主动澄清 ACI：把第 64 轮 APP 搬到语言层）**
直觉：第 64 轮既然能主动"压一压"测物理，语言层也能主动"问一句"消歧。当角色熵 H_role 高（"它"指杯子还是盒子？"左边"以谁为参照？"用锤子"是工具还是被递物？），不该猜，而应选**信息增益最大、人类负担最小**的澄清动作：是非问、二选一、指认、演示、请人改写。**ACI = Active Clarification Inquiry**，与 APP 同构：探针集从 {press,rub,tap,lift} 换成 {ask,which,point,demonstrate,rephrase}，目标从 Fisher 信息换成**角色熵的期望下降**，约束从力限换成**人类负担预算 B**。这把"歧义"从被动故障变成可主动消除的信息缺口。

**灵感 4（执行侧角色核验：不能只信解析器）**
直觉：角色绑得对不对，最终看"谁动了 / 谁收到了 / 什么变了"。让每个技能带**角色效果签名** eff；执行后由 EV_exec 观测对象级效果（哪个物体位移、哪个容器被填充、哪个人收到物体），反查角色是否按预期落地。**Role-slip 检测**比较意图角色框架的期望效果与实测效果签名：角色互换会让效果签名系统性对调，角色坍缩会让两个角色的效果不可区分。这把第 64 轮的接触证据 EV_exec 从"物理接触"扩展为"语义角色落地"。

**灵感 5（与原闭环咬合 → LIRI + 原位升级）**
- **USR/MEL → RGP**：语义推理后接角色框架解析与绑定，输出 F、绑定分布、H_role。
- **TSL → RSL**：技能签名从参数升级为角色签名（agent/patient/instrument/goal）。
- **CSP-F → CSP-L**：规划边携带角色绑定约束与一致性检查；不可达时插入 clarify 元技能。
- **AIC-F → AIC-L**：干扰集增 ASR 同音/漏字、否定注入、量词辖域、对抗角色互换、干扰实体。
- **OLP-F → OLP-L**：投影输入增角色特征 e_role，使语义相近指令的投影更平滑。
- **Shield-Skill → Role-Switch Shield**：执行前拦截未授权角色变更与低置信绑定。
- **J_grip → J_liri**：证书增 (role_frame_hash, binding_hash, ρ_role, H_role, clarify_log_hash, ρ_para, cf_audit, role_calib_ver)。

闭环：NL u → RGP 角色框架/绑定 →（H_role 高则 ACI 澄清）→ RSL/CSP-L 角色标注规划 → Shield-R → 执行 → EV_exec 角色效果核验 → role slip 回灌 RGP/CSP-L → AIC-L 认证 → J_liri。**第 64 轮是"几何-技能-干扰-接触"四层；LIRI 再加"语义角色"这一层，使"机器人做的确实是用户说的那件事"第一次进入证书链。**

## 1. 形式化定义（增量：定义 217–232）

- **定义 217（LIRI 闭环）**：LIRI = (LIRO, GRIP, RGP, ACI, RSL, CSP-L, RSE, AIC-L, J_liri)。定位：GRIP 的"语义角色接地"升级，全部新增组件挂载在第 64 轮骨架上；不变式：**语言解析/澄清/角色审计只在语义流；实时流只做角色一致性哈希比对、歧义门控、效果签名监控与角色切换屏蔽，零在线学习写操作**。
- **定义 218（角色框架与角色模式）**：角色集 ℛ = {agent, patient, theme, instrument, goal, source, recipient, location, manner, constraint}。角色框架 F = (p, ρ, C)：p 为谓词/动作类型，ρ: ℛ → (ℰ ∪ ⊥) × [0,1] 为角色-实体绑定及置信度，C 为约束（否定 ¬、量词 ∀/∃、时序 ≺、条件 →）。每个技能声明角色模式 role_sig，规定必需角色与类型 τ。
- **定义 219（角色解析与接地）**：给定指令 u、场景图 G（来自 LSF/MEL 的实体/属性/关系）、上下文 ctx，RGP 输出后验 P(F, ρ | u, G, ctx) = P(F|u)·Π_r P(ρ(r) | F, u, G)。每个必需角色的候选绑定用共形预测给出覆盖 1−α_role 的集合 𝒞_r；**确定性绑定**要求 |𝒞_r| = 1 且置信度 ≥ c_min。
- **定义 220（角色一致性）**：对时序计划 τ = (σ_1..σ_k) 及其角色框架序列 {F_i}，称角色一致当且仅当：**(C1 时序保持)** 对持久角色 r，若 F_i、F_j 中均非 ⊥ 且无显式变更算子，则 binding_i(r) = binding_j(r)；**(C2 指代保持)** 共指链实体身份不变；**(C3 单射)** r ≠ r' 且非语言显式允许时 binding(r) ≠ binding(r')；**(C4 改写不变)** 对 u' ∈ Paraphrase(u)，共享角色的绑定分布距离 ≤ ε_role。一致性裕度 ρ_role = 1 − max(C1..C4 的归一化违约度)。
- **定义 221（角色歧义与熵）**：H_role = H(binding | u, G) 为角色绑定后验熵（可分解为每角色熵与联合熵）；ambiguous ⇔ H_role > H* 或存在 |𝒞_r| > 1 的必需角色。
- **定义 222（角色效果签名与滑移检测）**：技能 σ 的角色效果签名 Eff(σ) = (moved(patient), transferred(theme, recipient), used(instrument), achieved(goal), …)，执行证据 EV_exec 给出实测签名 Ê。角色滑移统计量 S_slip = d(Eff(F), Ê)，区分**角色互换**（agent↔patient 签名对调）、**角色坍缩**（两角色效果不可分）、**工具/目标混淆**、**指代漂移**。
- **定义 223（ACI 主动澄清）**：澄清动作集 Q = {yes_no(r,e), which_of(r,{e_i}), point(r), demonstrate(σ), rephrase(u)}。选择 q* = argmax_{q∈Q} E[H_role − H_role | q] / cost(q)，s.t. burden(q) ≤ B_remain；仅当 H_role > H* 时触发；停止当 H_role ≤ H* 或预算耗尽；**禁止在 H_role > H_max 时静默执行**（失效安全方向固定为"问"）。
- **定义 224（RSL 角色标注技能库）**：σ = (name, role_sig, pre, eff, π_σ, cost, force_spec)。pre 增角色类型与绑定成立；eff 输出角色效果签名；π_σ 在 GRIP 的 (K, c, f) 上以角色参数化（patient 位姿、instrument 朝向、recipient 交付点）。
- **定义 225（CSP-L 角色条件规划）**：在 CSP-F 的层级 A* 上，技能边仅当角色模式可满足、ρ_role ≥ 0 且不引入未授权角色变更时加入；软代价增 λ_role·Σ_t hinge(−ρ_role,t)；不可达时插入 clarify 元技能或回退 safe_idle。
- **定义 226（反事实角色审计 CFA）**：对计划 τ 与角色框架 F，生成角色置换/交换的反事实指令集 {u^(π)}，仿真执行后要求效果签名随之改变；定义角色敏感度 S_role(τ,F) = E_{π≠id}[d(Eff(F^π), Eff(F))]；若 S_role ≈ 0 则判定"角色坍缩/规划忽略角色"，写入证书。
- **定义 227（语言鲁棒集与角色不变式）**：𝒫(u) = {被动化、同义替换、语序调整、指代改写、冗余修饰、标点/口语化}；𝒩(u) = 否定/量词辖域/条件扰动。要求对 u' ∈ 𝒫(u) 角色绑定不变（ρ_para ≥ 0），对 u' ∈ 𝒩(u) 角色绑定按语义正确改变（**不得把否定当肯定**）。
- **定义 228（角色解析校准）**：用 ECE 与共形覆盖度量 P(ρ*(r) ∈ 𝒞_r) ≥ 1−α_role；校准版本 role_calib_ver 入证书。
- **定义 229（AIC-L 语言干扰认证）**：ℰ_L = {ASR 同音/漏字, 干扰实体, 误导属性, 对抗角色互换, 否定注入, 量词歧义}；ρ_dir^L 在 ℰ_L 上重算；最坏情况要求角色绑定不翻转，或触发澄清。
- **定义 230（J_liri 证书）**：J_liri = (J_grip, role_frame_hash, binding_hash, ρ_role, H_role, clarify_log_hash, ρ_para, cf_audit, role_calib_ver)。Valid ⇔ Valid(J_grip) ∧ ρ_role ≥ 0 ∧ (H_role ≤ H* ∨ clarify_log 覆盖各方歧义) ∧ ρ_para ≥ 0 ∧ cf_audit 通过 ∧ role_calib_ver 有效。
- **定义 231（澄清预算与风险敏感门控）**：B 为人类负担预算（问题数/等待时间/打断次数）。仅当最坏角色误绑代价 ≤ c_tol 时允许静默；否则必须澄清。给出"问 vs 猜"的期望代价比较：E[cost(ask)] = c_ask + E[H_role 残差风险]，E[cost(guess)] = P(slip)·c_slip。
- **定义 232（LIRI 闭环算子）**：语义流 [NL→RGP→(ACI 澄清)→RSL/CSP-L 规划→Shield-R→执行首技能→EV_exec→RSE 角色核验→RGP/SSB 更新→AIC-L→J_liri]；实时流 [角色哈希比对→歧义门控→效果签名监控→角色切换屏蔽→π_σ1 派发→J_liri 构建]。

## 3. 保证概要与推导要点（完整推导见产物区）

- **引理 7（角色绑定覆盖与一致性收缩）**：若角色绑定集 𝒞_r 以 ≥1−α_role 覆盖真绑定、且角色模式两两可区分（类型/效果签名不混淆），则在 ρ_role ≥ 0 的计划内，发生未检出角色滑移的概率 ≤ α_role + α_slip。**一致性约束把"可能的绑定空间"缩成"计划内不变的绑定"，等价于给语义层加了一个可检验的球。**
- **引理 8（角色敏感性与滑移可检性）**：若不同角色在效果签名上可区分（d(Eff(r), Eff(r')) ≥ δ_eff），则任意非平凡角色置换 π 使 d(Eff(F^π), Eff(F)) ≥ δ_eff；当 δ_eff > 噪声 σ_e 时，S_slip 可在 O(σ_e² log(1/β)/δ_eff²) 步内检出。**反事实审计把"规划是否真的用了角色"变成可证伪命题。**
- **定理 7（ACI 澄清复杂度）**：设每次澄清至少带来 ΔH 的角色熵下降，则在可实现性假设下，达到 H_role ≤ H* 所需问题数 ≤ ⌈(H_0 − H*)/ΔH⌉，且 D-最优查询使该界最紧。人类负担 B 与残余风险之间满足 E[残余代价] ≤ c_slip·exp(−B·ΔH)。
- **定理 8（LIRI 端到端保证）**：Valid(J_liri) ⇒ GRIP 物理安全 ∧ 角色绑定集以 ≥1−α_role 含真绑定 ∧ 计划内角色一致（无未授权变更）∧ 歧义已澄清或不超阈值 ∧ 对改写集角色不变 ∧ 反事实审计通过。**证书链从"几何-技能-干扰-接触"扩到"几何-技能-干扰-接触-语义角色"五层。**
- **命题（一致性-覆盖性张力）**：过强的角色一致性会拒绝合法的角色转移指令（"把杯子给客人，再让客人把杯子给你"）；必须引入**显式角色变更算子**（"然后/接着/换成"）并区分其与滑移，否则一致性会误伤正常交互。
- **实时性**：角色哈希比对 <0.02ms、歧义门控 <0.01ms、效果签名监控 <0.1ms、角色切换屏蔽 <0.05ms，实时路径新增 ≤0.2ms，仍满足 2ms 契约（继承 A87，新增 A88）。

## 5. 本轮最大风险

**一句话**：角色一致性是一个建立在"角色标签良定义、解析器已校准"之上的语义不变量——若解析器系统性错误，系统会**"一致地错"**：稳定、可认证地执行一个错误绑定，而物理安全证书照常签发；同时过严的一致性约束会拒绝合法的角色转移与语用指令、造成澄清疲劳，使角色一致性从"语义接地真值"反变为新的单点语义故障源。

## 2. 形式化定义（完整版）

**定义 217（LIRI 闭环）** LIRI 是 GRIP 的"语义角色接地"升级：在第 64 轮"语义流 ∘ 实时流"骨架上挂载 RGP（角色解析/绑定）、RCC（一致性检验）、ACI（主动澄清）、RSE（执行侧滑移检测）、CFA（反事实审计），并原位升级 TSL→RSL、CSP-F→CSP-L、OLP-F→OLP-L、Shield-Skill→Shield-R、AIC-F→AIC-L、J_grip→J_liri。不变式：**语言解析、澄清、角色审计与规划只发生在语义流/低频线程；实时路径只做角色哈希比对、歧义门控、效果签名监控、角色切换屏蔽与首技能派发，零学习写操作。**

**定义 218（角色框架与角色模式）** 角色集 ℛ = {agent, patient, theme, instrument, goal, source, recipient, location, manner, constraint}。角色框架 F = (p, ρ, C)，其中 p 为谓词/动作类型（grasp/place/hand/insert/tool-use/…），ρ: ℛ → (ℰ ∪ ⊥) × [0,1] 为角色到实体（或未绑定 ⊥）的映射及置信度，C 为约束集：否定 ¬、量词 ∀/∃、时序 ≺、条件 →。技能 σ 声明角色模式 role_sig = {(r, τ_r, required)}，τ_r 为角色类型（object/person/place/tool），规定必需角色与类型兼容性。

**定义 219（角色解析与接地）** 给定指令 u、场景图 G、上下文 ctx（对话历史、共指表、任务栈），RGP 输出后验
P(F, ρ | u, G, ctx) = P(F | u) · Π_{r∈ℛ} P(ρ(r) | F, u, G)。
每个必需角色的候选绑定由共形预测给出集合 𝒞_r，满足 P(ρ*(r) ∈ 𝒞_r) ≥ 1−α_role。**确定性绑定**要求 |𝒞_r| = 1 且置信度 ≥ c_min；否则标记 ambiguous 并进入 ACI。RGP 同时输出指代链、否定/量词辖域标注与时序结构。

**定义 220（角色一致性 RCC）** 对时序计划 τ = (σ_1..σ_k) 及其角色框架序列 {F_i}，定义四个一致性条件：
- **(C1 时序保持)** 对持久角色 r，若 r 在 F_i、F_j（i<j）均非 ⊥，且 [i,j] 内无显式角色变更算子（"然后/接着/换成/再让"），则 binding_i(r) = binding_j(r)。
- **(C2 指代保持)** 共指链上的代词/省略必须回指同一实体身份，不得因新实体出现而漂移。
- **(C3 角色单射)** 若 r ≠ r' 且语言未显式允许（如反身"自己给自己"），则 binding(r) ≠ binding(r')。
- **(C4 改写不变)** 对 u' ∈ Paraphrase(u)，共享角色的绑定分布满足 D(binding | u) ≤ ε_role。
一致性裕度 ρ_role = 1 − max(δ_C1, δ_C2, δ_C3, δ_C4)，其中 δ_Ci 为对应条件的归一化违约度（违约步数/总步数或分布距离）。RCC 在语义流与实时流各跑一份：实时只比对角色哈希，违约即触发 Shield-R 与澄清。

**定义 221（角色歧义与熵）** H_role = H(binding | u, G) 为角色绑定后验熵，可分解为每角色熵 Σ_r H(ρ(r)) 与联合熵 H(ρ)。ambiguous ⇔ H_role > H* 或存在必需角色 |𝒞_r| > 1。区分**指代歧义**（𝒞_r 含多个实体）、**参照系歧义**（"左边"以观察者/物体/世界为参照）、**角色类型歧义**（"用锤子"中锤子是工具还是被递物）、**辖域歧义**（"所有红色的放这里"）。

**定义 222（角色效果签名与滑移检测 RSE）** 技能 σ 的角色效果签名 Eff(σ) = (moved(patient), transferred(theme, recipient), used(instrument), achieved(goal), …)，由技能语义与仿真预演给出。执行证据 EV_exec（继承第 64 轮）给出实测签名 Ê：对象位姿变化、容器填充、人手接收事件、工具接触事件。角色滑移统计量 S_slip = d(Eff(F), Ê)（角色类型加权的签名距离）。区分四类：
- **角色互换**：agent↔patient 或 theme↔recipient 签名对调；
- **角色坍缩**：两个不同角色的效果签名不可区分（规划忽略角色差异）；
- **工具/目标混淆**：instrument 被当作 patient 或反之；
- **指代漂移**：实测对象与绑定实体的身份不一致。
检出后回灌 RGP 重新绑定、触发 ACI，并把 role_slip 写入 J_liri。

**定义 223（ACI 主动澄清）** 澄清动作集 Q = {yes_no(r,e), which_of(r,{e_i}), point(r), demonstrate(σ), rephrase(u)}，代价 cost(q) 与人类负担 burden(q)（问题数、等待时间、打断次数）。选择
q* = argmax_{q∈Q} E[H_role − H_role | q] / cost(q)，s.t. burden(q) ≤ B_remain。
仅当 H_role > H* 时触发；停止条件：H_role ≤ H*、预算耗尽、或人类要求停止。**安全方向固定**：H_role > H_max 时禁止静默执行，必须先澄清；H_role ≤ H* 时可静默但记录 binding_hash 供审计。ACI 与 APP 同构：探针选择 ↔ Fisher 信息，澄清选择 ↔ 角色熵下降；力限 ↔ 人类负担预算。

**定义 224（RSL 角色标注技能库）** σ = (name, role_sig, pre, eff, π_σ, cost, force_spec)：
- pre_σ(F, x'')：在 TSL 前置条件上增"角色类型兼容 ∧ 必需角色已绑定 ∧ ρ_role ≥ 0"；
- eff_σ：输出角色效果签名（定义 222）；
- π_σ(x''; θ_σ)：在 (K, c, f_desired) 上以角色参数化——patient 的目标位姿、instrument 的抓握/朝向、recipient 的交付点、location 的参照系；
- 角色变更算子集：{then, next, instead, swap-to}，显式允许 C1 的绑定更新。
技能库离线蒸馏，部署后只在线微调 θ_σ；角色模式随技能固定、不可在线漂移。

**定义 225（CSP-L 角色条件规划）** 在 CSP-F 的层级 A* 上，技能边仅在以下条件成立时加入：role_sig 可被 F 满足 ∧ ρ_role ≥ 0 ∧ 不引入未授权角色变更。软代价增 λ_role·Σ_t hinge(−ρ_role,t)。若目标不可达，规划器可插入 clarify 元技能（调用 ACI）获取信息后重规划；仍不可达则回退 safe_idle。规划输出的 τ 附角色绑定快照 role_binding_snapshot，供 RSE 与证书使用。

**定义 226（反事实角色审计 CFA）** 对计划 τ 与角色框架 F，构造角色置换群 Π（角色互换、单角色对调、角色置 ⊥），生成反事实指令集 {u^(π)}，仿真执行得效果 {Eff(F^π)}。角色敏感度
S_role(τ,F) = E_{π≠id}[ d(Eff(F^π), Eff(F)) ]。
若 S_role < δ_sens（规划对角色交换不敏感），判定"角色坍缩/规划忽略角色"，J_liri 置 cf_audit=False。CFA 还检验"最小对照"：只改一个角色，效果必须相应改变，否则该角色在规划中被架空。

**定义 227（语言鲁棒集与角色不变式）** 改写集 𝒫(u) = {被动化、同义替换、语序调整、指代改写、冗余修饰、标点/口语化}；语义算子扰动集 𝒩(u) = {否定插入/删除、量词 ∀↔∃、条件方向翻转、时序交换}。要求：对 u' ∈ 𝒫(u)，角色绑定分布距离 ≤ ε_role（ρ_para ≥ 0）；对 u' ∈ 𝒩(u)，角色绑定必须按语义**正确改变**，尤其**不得把否定当肯定**（"不要拿红色" → 不得绑定红色为 patient）。𝒩 用于检验系统是否"只对措辞稳定、对语义敏感"。

**定义 228（角色解析校准）** 用期望校准误差 ECE = E[|conf − acc|] 与共形覆盖率 P(ρ*(r) ∈ 𝒞_r) 度量 RGP。要求 ECE ≤ ε_ECE、覆盖率 ≥ 1−α_role；校准方法（温度缩放/共形分位数）与版本号 role_calib_ver 入证书。**未校准的置信度不得用于风险门控**。

**定义 229（AIC-L 语言干扰认证）** 干扰集 ℰ_L = {ASR 同音/漏字, 干扰实体, 误导属性, 对抗角色互换, 否定注入, 量词歧义}。ρ_dir^L = 在 ℰ_L 上最坏情况的任务成功率裕度；对每个 η ∈ ℰ_L，要求角色绑定不翻转，或翻转被 RCC/RSE 检出并触发澄清。采样数在 AIC-F 的 96 上增 32（语言干扰），J_dir 增 role_calib_ver。

**定义 230（J_liri 证书）** J_liri = (J_grip, role_frame_hash, binding_hash, ρ_role, H_role, clarify_log_hash, ρ_para, cf_audit, role_calib_ver)。
验证规则：Valid(J_liri) ⇔ Valid(J_grip) ∧ ρ_role ≥ 0 ∧ (H_role ≤ H* ∨ clarify_log 覆盖各方歧义) ∧ ρ_para ≥ 0 ∧ cf_audit 通过 ∧ role_calib_ver 有效 ∧ binding_hash 与执行快照一致。审计链：role_frame_hash 追溯指令解析，binding_hash 追溯角色-实体绑定，clarify_log_hash 追溯澄清问答，cf_audit 追溯"计划是否真的用了角色"。

**定义 231（澄清预算与风险敏感门控）** 设人类负担预算 B（问题数/等待/打断），单次澄清代价 c_ask，角色滑移代价 c_slip，误绑最坏代价 c_worst。风险敏感规则：
- 若 c_worst > c_tol，则即使 H_role ≤ H* 也必须澄清（高风险任务宁可多问）；
- 若 c_worst ≤ c_tol 且 H_role ≤ H*，允许静默执行并记录；
- 期望代价比较：E[cost(ask)] = c_ask + E[残余风险 | 澄清后]，E[cost(guess)] = P(slip)·c_slip。选择期望代价更小者，但**永不越过 c_worst 的安全下界**。

**定义 232（LIRI 闭环算子）** 见 IP-223 伪代码。语义流：[NL u → RGP 角色框架/绑定 → RCC 一致性 → (ACI 澄清) → RSL/CSP-L 规划 → Shield-R → 执行首技能 → EV_exec → RSE 角色核验 → RGP/SSB 更新 → AIC-L → J_liri]；实时流：[角色哈希比对 → 歧义门控 → 效果签名监控 → 角色切换屏蔽 → π_σ1 派发 → J_liri 构建]。

### IP-214/215 RGP + RCC（角色解析与一致性检验）

```python
class RoleGroundedParser:
    """自然语言 → 角色框架 F=(p, rho, C) + 共形绑定集。语义流运行。"""
    ROLES = ('agent','patient','theme','instrument','goal','source',
             'recipient','location','manner')
    def parse(self, u, scene_graph, ctx, alpha_role=0.1):
        p, role_spans, constraints = self.srl(u, ctx)      # 谓词/角色跨度/算子
        bind = {}
        for r in self.ROLES:
            if r not in role_spans: bind[r] = (None, 0.0); continue
            cand = self.ground(role_spans[r], scene_graph, ctx)  # (entity, score)
            bind[r] = cand
        C_sets = {r: self.conformal_set(bind[r], alpha_role)
                  for r in role_spans}
        F = RoleFrame(p=p, rho=bind, C=constraints)
        H_role = self.entropy(bind, C_sets)
        return F, bind, C_sets, H_role


class RoleConsistencyChecker:
    """C1-C4：时序/指代/单射/改写不变。"""
    def check(self, frames, bindings, paraphrases, plan):
        d1 = self.temporal_violation(frames, bindings, plan)   # 未授权变更
        d2 = self.coref_violation(frames, bindings, plan)
        d3 = self.injectivity_violation(frames, bindings)
        d4 = max(self.dist(bindings, self.parse(u2)[1])
                 for u2 in paraphrases)
        rho_role = 1.0 - max(d1, d2, d3, d4)
        return rho_role, dict(C1=d1, C2=d2, C3=d3, C4=d4)
```

### IP-216 ACI（主动澄清）

```python
class ActiveClarifier:
    def choose(self, F, bind, C_sets, H_role, budget):
        if H_role <= H_STAR: return None, 0.0
        best, best_score = None, -np.inf
        for q in self.candidate_queries(F, bind, C_sets):
            if cost(q) > budget: continue
            H_post = self.expected_entropy(q, F, bind, C_sets)
            score = (H_role - H_post) / (cost(q) + 1e-9)
            if score > best_score: best, best_score = q, score
        if H_role > H_MAX and best is None:
            return BLOCK_AND_ASK, 0.0     # 高风险禁止静默
        return best, best_score

    def stop(self, H_role, budget):
        return H_role <= H_STAR or budget <= 0
```

### IP-219 RSE（执行侧角色滑移检测）

```python
class RoleSlipDetector:
    EFFECT_SIGS = {'grasp': ('moved',), 'place': ('moved','achieved'),
                   'hand': ('moved','transferred'), 'use': ('used','achieved')}
    def compare(self, F, skill, EV_exec):
        intended = self.effect_signature(F, skill)       # Eff(F)
        observed = EV_exec.role_effects()                # 对象/人手/容器事件
        S = self.weighted_sig_distance(intended, observed)
        kind = self.classify(intended, observed)         # swap/collapse/tool-goal/drift
        return S, kind
```

```python
def counterfactual_role_audit(plan, F, sim, roles):
    Eff0 = sim.run(plan, F)
    deltas = []
    for perm in role_permutations(roles):                # 单角色对照 + 互换
        if perm == identity: continue
        Fp = apply_role_perm(F, perm)
        Effp = sim.run(plan, Fp)
        deltas.append(effect_distance(Effp, Eff0))
    S_role = np.mean(deltas)
    return S_role >= DELTA_SENS, S_role
```

### IP-223 LIRI 闭环算子（整合）

```python
def LIRI_round(M, u, obs, budget):
    V, T, P, L, P_cloud, W_meas, tactile = obs
    # ———— 语义流 ————
    M.lsf.update_geometry(P_cloud)
    x_prime = M.lsf.fuse(M.usr.fuse(V, T, P, L))

    # 1) RGP：角色框架与共形绑定
    F, bind, C_sets, H_role = M.rgp.parse(u, M.scene_graph, M.dialog_ctx)
    rho_role, viols = M.rcc.check(M.frames + [F], M.bindings + [bind],
                                  M.paraphrases(u), M.plan_tau)

    # 2) ACI：歧义主动澄清
    if M.aci.stop(H_role, budget) is False:
        q, ig = M.aci.choose(F, bind, C_sets, H_role, budget)
        if q is BLOCK_AND_ASK:
            return M, SAFE_IDLE, build_j_liri(..., valid=False)
        ans = M.ask_human(q); budget -= M.cost(q)
        F, bind, C_sets, H_role = M.rgp.condition(F, ans)
        M.clarify_log.append((q, ans))

    # 3) RSL/CSP-L：角色条件规划
    tau, theta_bind = M.csp_l.plan(M.goal(F), x_prime, F, bind,
                                   rho_role, M.rsc.r)
    shield = role_switch_shield(tau, F, M.frames)       # 拦截未授权变更

    # 4) 实时执行
    K_safe, EV_exec, cert = realtime_step_liri(
        M, tau, theta_bind, x_prime, F, bind)

    # 5) 执行侧角色核验 + 更新
    S_slip, kind = M.rse.compare(F, tau[0], EV_exec)
    if S_slip > TAU_SLIP:
        M.frames = []; M.dialog_ctx.push(('role_slip', kind))
        H_role = M.rgp.requery(F, kind)                 # 触发澄清
    M.olp_l.online_step(M.olp_l.fuse_role(x_prime, F, bind), EV_exec)
    ok_cf, S_role = counterfactual_role_audit(tau, F, M.sim, M.roles)
    rho_dir_L = M.aic_l.certify(tau, F, bind, u, M.scene_graph, M.plan_tau)
    return M, K_safe, EV_exec, build_j_liri(
        cert, role_frame_hash=hash(F), binding_hash=hash(bind),
        rho_role=rho_role, H_role=H_role, rho_para=1 - viols['C4'],
        clarify_log_hash=hash(tuple(M.clarify_log)), cf_audit=ok_cf,
        S_role=S_role, rho_dir_L=rho_dir_L, role_calib_ver=ROLE_CALIB_VER)
```

## 4. 推导

**引理 7（角色绑定覆盖与一致性收缩）** 设对每个必需角色 r，共形集 𝒞_r 以 ≥1−α_role 覆盖真绑定 ρ*(r)，且角色模式两两类型可区分。则对角色一致的计划（ρ_role ≥ 0），真绑定落在计划所执行的绑定快照内的概率 ≥ 1−|ℛ|·α_role（联合界）；若 RSE 的签名区分度 δ_eff > 2σ_e，则未检出角色滑移概率再降。**一致性把"所有可能绑定"收缩为"计划内不变的绑定"，等价于在语义层构造了一个覆盖率可控的置信球。** ∎

**引理 8（角色敏感性与滑移可检性）** 若任意两个不同角色在效果签名上的距离 ≥ δ_eff，则任意非平凡角色置换 π 满足 d(Eff(F^π), Eff(F)) ≥ δ_eff。实测签名噪声有界 ‖Ê − Eff‖ ≤ σ_e 时，S_slip 在置换下与无滑移下的差 ≥ δ_eff − 2σ_e。对 δ_eff > 2σ_e，以 O(σ_e²·log(1/β)/(δ_eff−2σ_e)²) 个执行样本即可把两类分开。若 S_role < δ_sens，说明效果对角色不敏感，即"规划忽略角色"（角色坍缩），应拒发证书。∎

**定理 7（ACI 澄清复杂度与风险-负担权衡）** 设每次澄清在可实现性假设下使角色熵至少下降 ΔH（D-最优查询使 ΔH 最大），则达到 H_role ≤ H* 所需问题数 N ≤ ⌈(H_0 − H*)/ΔH⌉。若残余滑移概率随熵指数下降 P_slip ≤ exp(−c·H_role)，则给定负担预算 B = N·c_ask，残余风险 ≤ exp(−c·(H_0 − B·ΔH/c_ask))。因此**在 c_worst 超过 c_tol 时，增加澄清预算总能压低风险，而静默猜测的风险不随预算改善**——这给出风险敏感门控的理论依据（定义 231）。∎

**定理 8（LIRI 端到端保证）** 假设第 64 轮 A83–A87 及：
- **(A88)** RGP 的共形绑定集以 ≥1−α_role 覆盖真绑定，校准 ECE ≤ ε_ECE；role_calib_ver 有效。
- **(A89)** 角色效果签名对不同角色可区分（δ_eff > 2σ_e），RSE 能在 T_slip 内检出非平凡滑移。
- **(A90)** 角色变更算子（then/next/instead/swap-to）被正确解析，RCC 不把合法变更误判为违约。
- **(A91)** ACI 的澄清回答可靠（人类回答噪声 ≤ η_h），且 H_role > H_max 时系统必先澄清、不静默执行。
- **(A92)** CFA 的仿真与真实效果差异 ≤ δ_cf，S_role 的估计误差有界。
- **(A93)** 实时路径新增组件（角色哈希、歧义门控、效果签名监控、Shield-R）总延迟 ≤ 0.2ms，无学习写操作。

则：
1. **语义可接地**：真角色绑定以 ≥1−|ℛ|α_role 概率落在执行绑定快照内（引理 7）。
2. **角色可核验**：计划内无未授权角色变更（ρ_role ≥ 0），且执行侧滑移若发生可在 T_slip 内检出并触发澄清（引理 8）。
3. **歧义可主动澄清**：H_role > H* 时以 ≤ ⌈(H_0−H*)/ΔH⌉ 次询问降到阈值以下；高风险时绝不静默（定理 7）。
4. **反事实可证伪**：S_role ≥ δ_sens 保证计划对角色敏感，排除"角色坍缩"。
5. **五层证书链**：Valid(J_liri) ⇒ 几何/接触安全（GRIP）∧ 角色一致且接地 ∧ 歧义已处理 ∧ 改写不变 ∧ 反事实通过。
6. **实时性**：实时路径新增 ≤0.2ms，总路径仍 ≤2ms，零学习写操作（A93）。∎

**命题（一致性-覆盖性张力）** 记"角色必须一致"的硬约束集合为 𝒦_cons。合法角色转移指令（"把杯子给客人，然后让客人把杯子给你"）若不携带显式变更算子，会被 RCC 判为 C1 违约而拒绝；若为保覆盖性放宽 𝒦_cons，则滑移与合法变更不可区分。设合法变更占比 κ，则误拒率 ≥ κ·P(无变更算子)，误收率 ≥ (1−κ)·P(滑移未被 RSE 检出)。**二者不可同时为零，必须靠变更算子语法 + 执行侧签名 + 澄清三者联合折中。** ∎

**命题（角色熵与任务风险的错配）** H_role 只度量"绑定不确定"，不度量"绑错后的代价"。低熵但高代价的误绑（如把"给我"的 recipient 绑定为机器人自身）可能比高熵低代价的歧义更危险。因此证书必须同时含 H_role 与 c_worst 门控（定义 231），不能只优化熵。∎

## 7. 已知风险

**一句话**：角色一致性建立在"角色标签良定义、解析器已校准、效果签名可区分"之上——若解析器系统性错误，系统会**"一致地错"**（稳定、可认证地执行错误绑定，物理证书照常签发），而过严的一致性约束又可能拒绝合法的角色转移与语用指令、造成澄清疲劳；**角色一致性因此可能从"语义接地真值"反变为新的单点语义故障源**。

**次级风险与缓解**：
1. **一致地错（consistent-but-wrong）**：解析器若稳定地把 recipient 绑成 robot，RCC/C4 都"一致"，证书仍通过；缓解：CFA 反事实审计 + RSE 执行侧签名 + 定期人工抽检，且 J_liri 显式记录 binding_hash 与解析器版本，避免"一致性"冒充"正确性"。
2. **角色标签本身不适定**：开放任务（"把它弄好""整理一下"）没有清晰角色框架；缓解：对开放式指令退化为"意图-约束"弱框架，降低一致性要求并强制澄清/确认，而非硬套 SRL。
3. **澄清疲劳与交互成本**：频繁询问会降低可用性；缓解：自适应阈值 H*、批量澄清、把低成本歧义（不影响安全）延后；风险敏感门控只在 c_worst 高时强制问。
4. **合法角色转移被误拒**：如"先给它再拿回来"；缓解：显式变更算子（then/next/instead/swap-to）+ 指代链跟踪 + 允许受控的角色重绑定，并用 C1 的算子白名单区分滑移与变更。
5. **效果签名不可区分 / 感知缺失**：遮挡、透明容器、人手被遮挡导致 Ê 不准；缓解：多模态证据（视觉+触觉+力）、签名置信区间、不可观测时降级为"待确认"而非静默。
6. **否定/量词辖域的语言学难题**：深层辖域歧义可能连人类都难判；缓解：把辖域不确定转成显式澄清（"是所有红色的，还是只要一个？"），不强行解析。
7. **多语言/口语/ASR 噪声**：同音字改变角色（"给他"vs"给她"）；缓解：AIC-L 认证 + 语音置信度门控 + 关键角色二次确认。
8. **与 GRIP 的耦合失效**：角色错导致工具选错→接触力模型也错，CGG 可能把"工具错"误判为"几何幻觉"；缓解：把 role_slip 与 geo_degraded 联合判别，任一触发都进入保守/澄清，而不是互相甩锅。
9. **实时预算**：角色检查叠加 GRIP 已逼近 2ms；缓解：角色哈希用增量/缓存、RSE 与 GRIP 的 EV_exec 共享、Shield-R 用查表，必要时把 CFA 全部移出实时路径。
