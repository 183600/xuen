# 第 10 轮 · PSALM：本体感知锚定 + 物体级 SLAM 记忆——把真实世界泛化从“像素不变性”推进到“状态估计”

> 检索/复核日期：2026-10-27（UTC）。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮三个灵感词是「本体感知」「真实世界泛化」「SLAM」。上一轮 R3-VLA 的主线是训练侧不变性（Regroup/Rephrase/Recover）；本轮不推倒它，而是指出它的盲区：**不变性让策略对干扰“不敏感”，但没有给策略“场景状态”**。真实世界泛化的一部分不是识别问题，而是状态估计问题：物体被移动到哪里、抓取有没有打滑、相机/底座是否和模型以为了的一致。

## 0. 思考路径：三个词怎么走到 PSALM

1. **本体感知**：第一反应是“再加一路输入”。但本轮读到的证据（ThinkProprio、How Should VLA Use Proprioceptive State、ReViP、EyeRobot 2.0、Semantic Anchoring、RS-CL）说明，本体感知的价值不在“多一个模态”，而在两件事：**它是域不变的动作锚**（相对动作/相对位姿），以及**它是免费的接触/失败传感器**（动力学残差）。所以本体感知应该同时进“动作表示”和“运行时监测”，而不是只做一个 late conditioning vector。
2. **真实世界泛化**：R3-VLA 把它拆成 session/复述/扰动三种不变性；但官方 5 轴（位置/干扰物/背景/未见物品/人扰）里有 4 轴本质上是 **3D 物体状态变化**。2D 像素不变性可以让模型“不怕背景”，但不能让模型“知道杯子被移到了哪里”。Spa-Bench 的 ID→OOD 掉 27pp、RADAR 的 3D IoU 0.261→0.068、POGS/DREAM/ANCHOR 的物体记忆收益，都指向同一个结论：**真实世界泛化需要一个状态层**。
3. **SLAM**：桌面任务不需要建整张地图，也不需要激光 SLAM。这里的 SLAM 应该被重新定义为 **object-level local SLAM / scene memory**：桌面子地图 + 物体位姿图 + 夹爪/本体里程计 + 双目/腕部测量；人移动物体后能检测、更新、重定位。它直接对着位置、干扰物、背景、未见物品、人扰五轴。
4. **数据审计的修剪**：本轮把 HangCup 的 `meta/stats.json` 和 rows API 拆开看，发现 `action.pivot` 几乎是常数（dim2 std≈0.0072，dim4=0.15，dim6≈0.7384，其余维 std<1e-4），`state_torso`/`state_d435` 也几乎常数；演示基本是上半身桌面操作。**全身 pivot/腰腿不是本轮的主轴，砍掉。** 同时，公开榜单的 8 个模型 ×32 任务是 seeded demo：对榜首 MolmoAct2 的 8 个 2 步任务反推 `P(step2|step1)` 全部等于 0.6148–0.6150，这是生成器常数，不是真实模型行为；**不能拿榜单任务差异推断“最后一步最难”**。
5. **结论**：把 R3-VLA 保留为训练骨架，把 SURE-BT/AEH/VFCS 保留为运行时骨架，新增 **PSALM** 三层：P-Action（本体锚定相对动作）、P-Monitor（本体动力学残差）、P-SLAM Lite（桌面物体位姿记忆）。先做最便宜的两层，再把 SLAM 作为第二级；完整因子图只在标定/延迟/单模型合规门控通过后上。

## 1. 结论：下一分不在“更大的 VLA”，在“状态”

- R3-VLA 解决的是“训练分布里见过域偏移/复述/扰动”；它仍然是一个 **无场景记忆的观测到动作映射**。
- 官方 5 轴里，位置、干扰物、背景、未见物品、人扰，本质上都在改变 **物体的 3D 状态**；仅靠 2D 像素不变性，模型只能“重新猜”，不能“记住并更新”。
- 官方 API 只给 4 路 RGB + 本体感知 + 语言，**没有深度、没有触觉**；但头部左右相机是一对立体相机，这是唯一的深度来源。**本体感知是高频、域不变的锚；双目是物体级 SLAM 的测量；腕部相机是接触级的验证。**
- 因此本轮主押注升级为 **PSALM（Proprioceptive Scene Anchor & Localization Memory）**：
  1. **P-Action**：把动作从绝对位姿改成“相对当前本体感知的增量”，在服务端与实测状态合成绝对动作；减少标定/漂移/域偏移。
  2. **P-Monitor**：用官方数据自监督训练一个本体动力学残差模型，检测打滑、碰撞、卡住、人扰和 false completion；作为 chunk 可靠性和 BT 触发器。
  3. **P-SLAM Lite**：用头部双目 + 腕部相机 + 本体里程计维护桌面级物体位姿记忆；人物移动/遮挡后重新定位目标，给 BT/策略提供目标位姿和置信度。
- 完整的因子图/几何 token 是第三级，只在标定、延迟、单模型合规门控通过后上；不把“全 SLAM”当第一天的目标。
- 一句话：**R3-VLA 让策略“不怕变化”，PSALM 让策略“知道变化”。**

## 2. 本轮先核实：赛事/接口/数据/榜单

### 2.1 赛事身份与规则（未变）

- 32 任务、32000 演示（HF 精确 33,276 episodes / 18,282,246 frames / 169.28h / 30fps）、G1 + Dex1、单模型通才赛道、选手自部署 + 远程 API、每任务 10 次、5 类泛化各 2 次、180s、成功率→步骤分→提交日期（[S1][S2][S3]）。
- 规则原文只限制“同一模型完成全部任务，不得混用多个模型”；**对模型类型不设限（World Model、VLA 均可）**。没有明确说“禁止经典几何/标定代码”，但也没有明确允许外部数据；本轮默认只用官方 33k，经典几何作为确定性代码，不引入第二个学习模型（[S2][S3]）。
- 单模型边界是本轮最大的合规风险：P-Action/P-Monitor 可以挂在同一个 checkpoint 上；P-SLAM Lite 是确定性几何（OpenCV/PCL 级别），不是学习模型。若组委会把“几何模块”也算模型，则退回只做 P-Action + P-Monitor，或向组委会书面确认。

### 2.2 提交接口 v2：本体感知/双目/无深度

- 2026-08-21 的 v2 commit 把接口改成“按 `obs_delta_indices` 选择观测 + 时间堆叠 + 测试端图像缩放”；这使本体感知历史第一次成为可配置输入（[S7]）。
- 观测：4 路 RGB（`cam_left_high`/`cam_right_high`/`cam_left_wrist`/`cam_right_wrist`）、左右臂 7、左右夹爪 1、`lower_body` 15、左右 EE pose 6、语言。**没有深度图、没有触觉、没有力传感器**；头部左右相机是立体对，腕部是单目（[S7] §2）。
- 动作：左右夹爪、`action.pivot` 7、以及 joint 或 ee 二选一的双臂动作；chunk 固定、整块执行；token 双校验；N 端口 8765..；每 episode reset；§6 记录延迟/波动/动作规律性（[S7]）。
- **关键工程事实**：`obs_delta_indices` 的 key 决定哪些观测被发送；我们可以只请求本体感知历史（例如 arms [-4,-2,0]、lower_body [-2,0]、EE pose [-2,0]），不增加图像带宽；`image_resize` 可按相机分别设置（[S7] §2）。

### 2.3 数据里有什么：比 API 多，但上半身为主

- 数据 32 个 HF 仓库，33,276 episodes；特征包含 4 路相机、左右臂、夹爪、`lower_body` 15、左右腿 6+6、腰 3、EE base/torso、torso/D435 状态、`recomputed_ee_valid`；动作包含 joint/EE、`lower_body`、`pivot`、`gripper_controls`、`base_command`（[S5][S6]）。
- 本轮实测（HangCup `meta/stats.json` + rows API）：
  - `lower_body` 确实是 `left_leg(6) + right_leg(6) + waist(3)` 的拼接；API 只暴露这个 15 维，不单独暴露腿/腰。
  - `action.pivot` 几乎是常数：dim2 std≈0.0072（q01/q99≈-0.0011/+0.0020），dim4=0.15，dim6≈0.7384，其余维 std<1e-4；`state_torso`/`state_d435` 也几乎常数。**这说明演示基本是上半身桌面操作，不是全身 loco-manipulation；押注 pivot/腰腿是不划算的。**
  - `recomputed_ee_valid` 在样本中为 1；可作为数据质量过滤，但需要统计全量 invalid 比例。
- 数据 schema 仍有坑：`meta/episodes` 的 `tasks` 字段在 PlugCharger 是 string、其余是 list；naive loader 会取到首字符（沿用上一轮结论）。
- 数据仍有 192 个采集 session、每任务 5 条官方复述、30/32 任务有人扰备注、9 个任务缺 `unseen_object_3`、步骤 2–5 不等（沿用上一轮审计；本轮不重复全量解析）。

### 2.4 榜单仍是 seeded demo，而且能证明它是生成的

- `leaderboard_data.json`：`generated_from: "gen_leaderboard.py"`，`generated_at: null`；8 个模型 ×32 任务；榜单页/首页仍“即将发布”；runs 页 256/256 但底部仍“即将发布”；details 页是占位视频（[S8][S9]）。
- 更强的证据：对榜首 MolmoAct2 的 8 个 2 步任务，反推 `P(step2|step1)` 全部等于 **0.6148–0.6150**（例如 HangCup 27.29/44.39=0.6148，PackDoll 37.01/60.19=0.6149）。这不是真实模型会有的巧合，而是生成器用了固定条件成功率。
- 因此：
  - **29.7% 不是真实头部**，不能用来推断哪个模型/架构更强；前 3 名差距 1.2/0.6pp，小于 320 次、p≈0.3 的 SE≈2.56pp，本来也不可区分。
  - 也不能用榜单任务差异推断“最后一步最难”；那只是生成器的 61.5% 常数。
  - 但“真实真机 VLA 的成功率在 20–30% 量级”仍与外部真机基准一致（Spa-Bench OOD 40.7–52.0%、RADAR 3D IoU 0.261→0.068、SO-101 execution instability 主导），可以作为难度先验（[S64][S65][S66]）。

## 3. 上一轮 R3-VLA 的盲区：不变性 ≠ 状态

R3-VLA 的三个不变性（session/复述/扰动）都在训练分布里做文章；它们让模型对“见过的变化”更稳，但没有解决三件事：

1. **物体被移动后，模型没有持久记忆**。每帧观测是独立的；人把杯子从 A 移到 B，策略只能从当前像素重新猜，或者继续执行旧轨迹。POGS 用持久物体表示在人物移动后连续 12 次 reset、恢复 80% in-grasp 扰动；DREAM 用时空语义记忆把长程成功率从 40–60% 提到 55–70%；ANCHOR 用物理锚点把 53.3% 提到 71.7%，扰动恢复 71.4%（[S60][S61][S62]）。
2. **抓取/接触失败没有本体层面的检测**。视觉可能被手/物体遮挡，但关节/EE/夹爪的本体信号仍在；ReViP 指出状态主导会造成 false completion，反过来也说明本体信号必须与视觉重新平衡；SO-101 基准把 execution instability 列为主导失败源（[S52][S66]）。
3. **2D 像素不是 3D 状态**。Spa-Bench 在保持物体/动作训练支持的情况下，把空间配置从 ID 换到 OOD，成功率从 67.5–73.3% 掉到 40.7–52.0%；RADAR 在传感器噪声下 3D IoU 从 0.261 掉到 0.068；GeoAlign 用状态引导的几何 token 在 8 个真机 ALOHA 任务到 78.8%（[S64][S65][S53]）。

所以本轮不是“再加一个不变性”，而是加一个 **状态层**：本体感知提供高频锚，SLAM/物体记忆提供 3D 状态，VLA 仍负责语义和技能。

## 4. PSALM：三层，逐级上

### 4.1 P-Action：本体感知锚定的相对动作

**问题**：官方动作是绝对 EE pose 或绝对 joint target；模型在训练集上学会“绝对坐标”，到真机上底座/相机/桌面高度稍有不同，绝对坐标就偏；chunk 内误差还会累积（上一轮 S36）。

**做法**：
- 训练时把绝对动作转成相对当前实测状态的增量：
  - EE：`Δξ* = log(T_ee_current^{-1} T_ee_target)`；推理时 `T_cmd = T_ee_current exp(Δξ)`。
  - Joint：`Δq* = q_target - q_current`；推理时 `q_cmd = q_current + Δq`。
- 模型同时输出绝对头和相对头；推理默认用相对头，绝对头作为 fallback/正则。
- **Anchor perturbation**：训练时给本体锚 `s_t` 加小扰动 `ε`，要求 `compose(s_t+ε, f(o,s_t+ε))` 与 `compose(s_t, f(o,s_t))` 一致；这让模型学会“用锚”，而不是背绝对坐标。
- 对 chunk 内所有动作都用**同一个当前锚**（star parameterization），下一 chunk 重新锚定；避免逐步复合误差。

**证据**：EyeRobot 2.0 把 gripper proprioception/action 规范化到 fixation-relative SE(3) 帧，压缩动作分布；Semantic Anchoring 在动作表示上做锚定，真机 OOD +21.5%；RS-CL 用本体状态距离做对比正则，真机 45.0→58.3%；“How Should VLA Use Proprioceptive State?” 建议当前帧进 VLM、短历史进 action head（[S54][S55][S56][S51]）。

**预期**：+1–2pp；主要收益是跨 session/真机漂移和动作平滑，不是 clean 上的大跳。

### 4.2 P-Monitor：本体动力学残差 = 免费的失败检测器

**问题**：没有力/触觉，怎么知道抓滑了、撞了、卡住了、被人碰了？视觉可能被遮挡；动作块又是开环执行。

**做法**：
- 用官方数据自监督训练 `g_φ(s_{t-H:t}, a_{t-H:t}) -> ŝ_{t+1}`；残差 `r_t = ||s_{t+1} - ŝ_{t+1}||_{Σ^{-1}}`，按速度/相位归一化。
- L0（零新模型）：用常数速度/加速度或关节空间一阶模型做残差；先上线 log-only，验证 false positive。
- L1（同 checkpoint 辅助头）：在 VLA 的 action expert 上挂一个小动力学头；只加辅助损失，不引入第二个在线模型。
- 阈值：按任务/session 校准，EVT/分位数 + CUSUM 持续性；只在连续 N 帧超阈值时触发 `verify/careful`，不直接 abort。
- 用途：
  - chunk 可靠性 → AEH 截断到最后一个安全动作；
  - BT 谓词 `slip/stuck/unexpected_contact/human_bump`；
  - false completion 检查：本体说“到位”，视觉/物体记忆说“没到位”时，触发复核。

**证据**：ReViP 的 false completion 与 vision-proprioception 失衡；ANCHOR 用低层信号（夹爪电流/状态不匹配）做局部恢复；SO-101 把 execution instability 列为主导失败；ThinkProprio 证明本体早期融合能改变视觉 token 选择（[S52][S62][S66][S50]）。

**预期**：人扰轴 +2–4pp；false completion 下降；延迟 <1ms。

### 4.3 P-SLAM Lite：桌面级物体位姿记忆

**问题**：官方 5 轴里的位置/干扰物/背景/未见物品/人扰，都是 3D 物体状态变化；2D 策略没有持久记忆。

**做法**：
- **传感器**：头部左右相机做立体（SGBM/立体匹配）→ 点云；腕部相机做近距验证；本体 EE/关节做里程计。
- **表示**：桌面子地图，不建整张 SLAM 地图。节点 = 目标/干扰物/夹爪位姿；因子 = 本体里程计、立体视觉位姿、抓取约束（夹住时物体随夹爪）、桌面平面先验。
- **初始化**：第一帧/前几帧做桌面平面 RANSAC + 欧式聚类，得到物体簇；用 VLA 自己的语言-视觉特征/动作注意力选目标簇（不引入外部检测器）。
- **跟踪**：物体在桌上时静态先验；夹住时 `T_obj = T_gripper * T_obj^gripper`；人移动时视觉位姿跳变 → 标记 `moved` 并更新；遮挡/丢失 → `occluded/lost` + 记忆引导搜索。
- **重定位**：在最后已知位姿附近采样视角/扫描；特征匹配 + PnP/RANSAC；找不到则让 VLA 搜索。
- **输出**：目标位姿 + 协方差 + 置信度 + last_seen，给 BT（`moved/occluded/lost`）和/或作为几何 token 给 VLA（第三级）。
- **范围**：先做刚性、有纹理物体（约 18–20 个任务）；透明/反光/布料/拉链用腕部 servoing + P-Monitor fallback，不硬上。

**证据**：POGS 持久物体表示 + 人物移动恢复；DREAM 时空语义记忆 + 混合定位；ANCHOR 物理锚点；BOPI 在线物体 belief；StereoPolicy/ExStereo 证明双目对操作有效；AnchorVLA4D 用首帧 anchor + 当前帧解决遮挡/空间迷失；Spa-Bench/RADAR 证明空间 grounding 是独立瓶颈（[S60][S61][S62][S63][S58][S59][S57][S64][S65]）。

**预期**：位置/人扰轴 +2–5pp；重定位成功率 >70%；延迟通过异步关键帧控制。

### 4.4 P-SLAM Full（第三级，门控）

- 因子图 + 几何 token 进 VLA；用物体位姿 token 让策略直接“看到”3D 状态；训练时对物体位姿加噪/丢 token，防止过拟合。
- 只在 Lite 的标定/延迟/收益门控通过后做；否则停在 Lite。
- 合规：几何 token 用同一 checkpoint 的编码器/辅助头；不引入第二个学习模型；经典几何是确定性代码。

## 5. 五轴映射：PSALM 正好对着官方 5 类泛化

| 官方轴 | 失败机制 | PSALM 机制 |
|---|---|---|
| 位置 | 目标/容器平移，绝对动作去旧位置 | 物体位姿记忆 + 相对动作锚定 |
| 干扰物 | 多物体混淆/遮挡 | 多物体簇记忆 + VLA 语言特征选目标 |
| 背景 | 桌布/纹理/光照变化 | 桌面平面/几何 canonicalization，不记像素 |
| 未见物品 | 外观/形状/材质变化 | 几何聚类 + 腕部 servoing；不依赖类别先验 |
| 人扰 | 物体被移动/拿走/追加 | 本体残差 + 视觉跳变检测 + 重定位/搜索 |

这张表是本轮的核心：不是“再训一个更大的模型”，而是把 5 轴分别映射到可测试的状态估计模块。

## 6. 头部方案/瓶颈：只能分析“共享约束”，不能分析 seeded 数字

  1. 2D→3D 的几何/位姿；
  2. 物体/场景的持久状态；
  3. 接触/失败的在线检测；
  4. 开环 chunk 的误差累积。
- 这也解释了为什么“换个更大的 VLA”边际收益有限：接口没有给 3D 状态，模型只能从像素里猜；猜错一次，后面全错。PSALM 是在接口允许的范围内补这四件事。

**评分算术**：

```text
总 episode = 32 × 10 = 320
单任务权重 = 1/32 = 3.125pp
单轴权重 = 2/10 = 20% = 64 episodes
单任务内分辨率 = 1/10 = 10%（任务内）
全局单 episode 分辨率 = 1/320 = 0.3125pp

S = (1/32) Σ_t (1/10) Σ_r 1[all steps completed]
P = (1/32) Σ_t (1/10) Σ_r Σ_i w_{t,i} 1[step i completed]
rank = lexicographic(S, P, submission_date)
```

**单模型边界（本轮重点）**：

- 规则只限制“同一模型完成全部任务，不得混用多个模型”；**没有限制模型架构**（[S2][S3]）。

### 3.2 P-Action：本体感知锚定的相对动作

#### 3.2.1 动机

官方动作是绝对 EE pose 或绝对 joint target。绝对动作把“机器人底座/相机/桌面”的坐标系写死在训练分布里；真机 rig 一变，动作就偏。相对动作以**实测本体状态**为锚，模型只预测“从当前状态出发的增量”，坐标误差被锚吸收。

#### 3.2.2 数学

设当前实测锚为 `s_t`（EE pose `T_t` 或关节 `q_t`），模型输出增量 `Δ_t`：

```text
EE:    Δξ_t = f_θ(o_t, l, s_t)          # 6D twist in current EE frame
       T̂_t = T_t · exp(Δξ_t)            # compose to absolute target
       Δξ*_t = log(T_t^{-1} · T*_t)      # training target

Joint: Δq_t = f_θ(o_t, l, s_t)
       q̂_t = q_t + Δq_t
       Δq*_t = q*_t - q_t
```

损失：

```text
L_act = ||T̂_t − T*_t||_SE3 + λ_rel ||Δξ_t − Δξ*_t||²
      + λ_abs ||T_abs_t − T*_t||²        # absolute head as regularizer/fallback
```

**Anchor perturbation / equivariance**：

```text
ε ~ small rigid transform (1–5mm, 0.5–2°)
L_eq = || compose(s_t ⊕ ε, f(o_t, l, s_t ⊕ ε))
        − compose(s_t, f(o_t, l, s_t)) ||²
```

直觉：锚变了，模型应该输出相反的增量，使最终绝对动作不变；这教会模型“用锚”，而不是背绝对坐标。

#### 3.2.3 Chunk 参数化

对 chunk 内第 `i` 个动作，全部用**同一个当前锚** `s_t`：

```text
T̂_{t+i} = T_t · exp(Δξ_{t+i}),  i = 1..T_a
```

下一 chunk 用新的实测 `s_{t+T_a}` 重新锚定。这样 chunk 内不会逐步复合误差；chunk 间由实测状态重置。

#### 3.2.4 伪代码

```python
def train_step(batch):
    o, l, s_t, a_star = batch
    delta_star = se3_log(se3_inv(s_t.ee) @ a_star.ee)
    delta_pred, abs_pred = model(o, l, s_t)
    a_pred = s_t.ee @ se3_exp(delta_pred)
    loss = se3_dist(a_pred, a_star.ee) \
         + lam_rel * mse(delta_pred, delta_star) \
         + lam_abs * se3_dist(abs_pred, a_star.ee)
    eps = sample_small_rigid()
    delta_eps = model(o, l, s_t.ee @ eps).delta
    a_eps = (s_t.ee @ eps) @ se3_exp(delta_eps)
    loss = loss + lam_eq * se3_dist(a_eps, a_pred)
    return loss

def get_action(obs):
    s_t = parse_proprio(obs)
    delta = model(obs, s_t).delta          # relative by default
    a = s_t.ee @ se3_exp(delta)
    a = clamp_to_workspace(a)
    return make_chunk(a, T_a)              # absolute targets, API-compliant
```

#### 3.2.5 设计选择

- **EE 优先**：官方支持 `ee` 控制；相对 SE(3) 动作最自然。Joint 空间作为消融/fallback。
- **双头**：相对头默认；绝对头在锚无效（`recomputed_ee_valid=0`、关节异常）时 fallback。
- **夹爪**：保持绝对开合命令；不参与相对锚定。
- **pivot/lower_body**：保持实测/常数；不主动动。
- **平滑**：对 `Δξ` 做低通/限幅；chunk 间用上一块末动作做 continuity check；避免 §6 的动作规律性问题。

### 3.3 P-Monitor：本体动力学残差

#### 3.3.1 动机

没有力/触觉，视觉又可能被手/物体遮挡；但关节、EE、夹爪的本体信号一直在。抓滑、碰撞、卡住、被人碰，都会让“下一步本体状态”偏离“按当前动作预测的状态”。这个残差是免费的失败信号。

#### 3.3.2 数学

```text
Dynamics:  ŝ_{t+1} = g_φ(s_{t-H:t}, a_{t-H:t})
Residual:  r_t = || s_{t+1} − ŝ_{t+1} ||²_{Σ^{-1}}
Normalize: ρ_t = r_t / (||v_t|| + ε)        # v_t = joint/EE velocity
Threshold: τ = Q_{1−α}(ρ_calib)             # per task/session; or EVT
CUSUM:     C_t = max(0, C_{t−1} + ρ_t − μ − k)
Alarm:     d_t = 1[C_t > h and consecutive > N]
```

#### 3.3.3 两级实现

| 级别 | 模型 | 成本 | 用途 |
|---|---|---|---|
| L0 | 常数速度/加速度/一阶关节模型 | 0 训练；CPU <1ms | log-only；先验证 false positive |
| L1 | 同 checkpoint 辅助动力学头（GRU/MLP 1–3M） | 与 VLA 联合训练 | 更细的接触/滑移检测 |
| L2 | 视觉-本体联合残差（腕部特征 + 本体） | 中等 | 遮挡下的 false completion 复核 |

**L0 残差**：

```text
ŝ_{t+1} = s_t + (s_t − s_{t−1})          # constant velocity
or ŝ_{t+1} = s_t + a_t · Δt              # action-conditioned first-order
ρ_t = ||s_{t+1} − ŝ_{t+1}|| / (||s_{t+1} − s_t|| + ε)
```

#### 3.3.4 阈值与误报控制

- 按任务/阶段/夹爪状态分层校准；抓取接触瞬间的残差是“预期接触”，不应报警。
- 用 **EVT/分位数** 设阈值；用 **CUSUM** 要求持续性；用 **conformal** 控制 false positive。
- 只在关键状态（接近、接触、插入、放置、人扰后）启用动作干预；其他时候 log-only。
- 报警动作分级：`log → verify → careful → recover → abort`；不直接 abort。

#### 3.3.5 伪代码

```python
def monitor_step(s_hist, a_hist, s_next):
    s_hat = dynamics(s_hist, a_hist)          # L0 or L1
    r = mahalanobis(s_next, s_hat, sigma)
    rho = r / (norm(velocity(s_hist)) + eps)
    cusum = max(0.0, cusum + rho - mu - k)
    if cusum > h and consecutive(rho > tau) >= N:
        return Alarm(level="verify", score=rho)
    return None

def chunk_policy(alarm, chunk):
    if alarm is None:
        return chunk
    if alarm.level == "verify":
        return chunk[:safe_prefix(chunk)] + hold_tail(chunk)
    if alarm.level == "careful":
        return chunk[:safe_prefix(chunk)] + retreat_tail(chunk)
    return recover_bt(alarm)
```

### 3.4 P-SLAM Lite：桌面级物体位姿记忆

#### 3.4.1 范围声明

这里的 SLAM 不是建整张地图，也不是激光 SLAM；它是 **object-level local SLAM / scene memory**：

- 世界坐标系 = 桌面坐标系（由桌面平面估计）。
- 节点 = 目标物体、干扰物、夹爪、相机。
- 因子 = 本体里程计、立体视觉位姿、抓取约束、桌面平面先验。
- 只维护任务相关的 5–20 个物体；不建稠密地图；内存 <100MB。

#### 3.4.2 传感器与初始化

```text
Head stereo:  cam_left_high + cam_right_high
  → rectify → SGBM disparity → point cloud
  → RANSAC table plane → table frame T_table^base
  → Euclidean clustering → object clusters {C_i}
  → ORB/AKAZE features + centroid + bbox + color histogram

Wrist cameras: cam_left_wrist / cam_right_wrist
  → close-range verification / servoing
  → contact/slip evidence

Proprioception: arms + grippers + lower_body + EE poses
  → high-rate odometry / grasp constraint
```

**目标选择（不引入外部检测器）**：

- 用 VLA 自己的语言-视觉特征（同一 checkpoint）对每个 cluster crop 打分；或
- 用 VLA 预测的 grasp point / action trajectory 选择最近 cluster；或
- 规则化颜色/形状先验（仅作 fallback）。
- 不用 CLIP/GroundingDINO/SAM 等外部模型。

#### 3.4.3 因子图

```text
State: X = { T_table^obj_i, T_base^gripper, T_base^cam }
Factors:
  e_proprio = log( (T_base^gripper(t+1))^{-1} T_base^gripper(t) · ΔT_proprio )
  e_stereo  = z_i − π( T_base^cam · T_table^obj_i )
  e_grasp   = log( (T_base^gripper)^{-1} T_table^obj_i · T_obj^gripper )
  e_table   = n^T p_j + d,  p_j ∈ table points
MAP: X* = argmin Σ ||e||²_Σ
```

桌面任务可以进一步简化：

- 机器人底座固定 → `T_base^table` 固定；相机外参固定。
- 物体在桌上 → 静态过程模型；夹住 → 由夹爪位姿决定；人移动 → 视觉跳变。
- 每个物体一个 EKF/pose filter；不需要全局 iSAM。


**重定位**：

- 在最后已知位姿附近采样 3–5 个视角（头部/腕部/小臂微动）。
- 特征匹配 + PnP/RANSAC；或点云 ICP（刚性物体）。
- 成功 → 更新 pose/cov；失败 → 让 VLA/BT 做搜索；不要无限重试。
- 对透明/反光/无纹理：用腕部边缘/背景减除；仍失败则 fallback 到 P-Action/P-Monitor。

#### 3.4.5 输出给策略/BT

```text
SceneMemory:
  target: {pose_table, cov, confidence, last_seen, state}
  distractors: [...]
  gripper: {pose_base, attached_object}
  events: moved / occluded / lost / reacquired
```

- **BT**：`moved` → 重新对准；`occluded` → 等待/换视角；`lost` → 记忆引导搜索；`reacquired` → 继续。
- **VLA**：第三级才把 object pose token 喂进去；Lite 先只给 BT/waypoint。
- **Action**：P-Action 的锚 + P-SLAM 的目标位姿可以组合成 object-centric target；但先不要改 VLA 输出，先用 BT 修正。

#### 3.4.6 伪代码

```python
class SceneMemory:
    def __init__(self, calib):
        self.calib = calib
        self.table = None
        self.objects = {}
        self.events = []

    def update(self, obs):
        if self.table is None:
            self.table = estimate_table(stereo_cloud(obs))
        if not is_keyframe(obs):
            return
        clusters = cluster_objects(stereo_cloud(obs), self.table)
        for c in clusters:
            obj = self.match_or_add(c)
            obj.pose = c.pose
            obj.cov = c.cov
            obj.last_seen = now()
        self.update_grasp(obs)
        self.detect_moved_or_lost()

    def target_pose(self, language):
        scores = vla_score_clusters(language, self.objects)  # same checkpoint
        return self.objects[argmax(scores)].pose
```

### 3.5 P-SLAM Full（第三级，门控）

- 把物体位姿编码成 8–16 个 geometry token，注入 VLA 的 action expert；参考 GeoAlign 的 state-guided geometry token。
- 训练时对物体位姿加噪（1–3cm/2–5°）、随机丢 token、随机遮挡；防止策略过度依赖完美位姿。
- 只做 2–4 个几何关键任务（插头、网线、试管、叠碗）作为试点；不要全 32 任务铺开。
- 门控：Lite 重定位 >70%、p99 延迟 <chunk、单模型审计通过、真机调试槽至少 2 次。
- 合规：几何 token 用同一 checkpoint 的视觉编码器/辅助头；不引入第二个学习模型。

### 3.6 与 R3-VLA / SURE-BT 的集成

| 层 | R3-VLA | PSALM | 集成点 |
|---|---|---|---|
| 训练 | Regroup/Rephrase/Recover | P-Action 相对头 + P-Monitor 动力学头 | 同一 checkpoint；共享 backbone；辅助损失 |
| 推理 | — | P-Action 合成绝对动作 | `get_action` 内确定性合成 |
| 运行时 | SURE-BT/AEH/VFCS | P-Monitor 残差 + P-SLAM 事件 | BT 谓词/恢复算子；AEH 截断；VFCS tie-break |
| 评测 | DGS-32 | DGS-32+ 状态留出 | 同一 320 矩阵 + 状态扰动 |

**BT 新增谓词**：

```text
slip(t)        := P-Monitor residual spike while gripper closed
stuck(t)       := residual high + EE velocity ~0 for N frames
moved(t)       := ||predicted object pose − visual pose|| > δ_move
occluded(t)    := no visual measurement for > T_occluded
lost(t)        := no visual measurement for > T_lost
reacquired(t)  := match confidence > c_reacq
false_done(t)  := VLA says done but target pose not at goal
```

**AEH 集成**：

- 原来的 AEH 用动作自注意力/两样本方差估可靠前缀；现在加 P-Monitor 残差：残差尖峰 → 截断到最后一个安全动作。
- 安全端点：保持/回撤/预放置；不可逆任务用保持，不用“继续推”。

**VFCS 集成**：

- 关键状态 K=2 选块；tie-break 用 P-SLAM 的目标位姿一致性 + 动作平滑度。
- 只在接触/插入/放置/人扰后触发；p99 不达标就退回 K=1。

### 3.7 单模型合规矩阵

| 组件 | 类型 | 是否学习 | 合规说明 |
|---|---|---|---|
| WLA-1.0-Base | 唯一 checkpoint | 是 | 主体 |
| P-Action 相对头 | 同 checkpoint 辅助头 | 是 | 共享 backbone |
| P-Monitor L1 | 同 checkpoint 辅助头 | 是 | 共享 backbone |
| P-Monitor L0 | 经典残差 | 否 | 确定性代码 |
| P-SLAM Lite | 经典几何 | 否 | 确定性代码；无学习权重 |
| P-SLAM Full | 同 checkpoint 几何 token | 是 | 共享 backbone |
| SURE-BT/AEH/VFCS | 确定性代码 | 否 | 可审计 |
| 外部 LLM/VLM/检测器 | 默认不用 | — | 需披露/询问 |
| 外部数据 | 默认 OFF | — | 只用官方 33k |

### 4.1 `metadata` 示例

```python
metadata = {
    "control_space": "ee",
    "obs_delta_indices": {
        "observation.language": [0],

        "observation.images.cam_right_high": [0],

        "observation.state.lower_body": [-2, 0],
        "observation.state.left_ee_pose_gripper_base": [-2, 0],

    "image_resize": {
        "observation.images.cam_left_high": [240, 320],

```

注意：

- `obs_delta_indices` 的 key 决定哪些观测被发送；不要声明不需要的键。
- 头部左右必须**同分辨率**，否则立体标定/rectification 失效。
- 腕部可以更低分辨率；但 P-SLAM 近距验证需要足够纹理。
- `action_chunk_size` 建议 8；T_a=8 → 267ms @30Hz；T_a=16 → 533ms。
- `reset()` 清空 SceneMemory、P-Monitor 的 CUSUM、P-Action 的上一块锚。

### 4.2 立体标定与深度

**离线标定**：

- 用官方数据的 `head_stereo_left/right` 估计双目内参/外参/基线；用棋盘格或自标定。
- 用 `cv2.stereoRectify` + `cv2.initUndistortRectifyMap` 预计算映射。
- 用 SGBM/BM 生成视差；`Z = f·B/d`；点云转到桌面坐标系。
- 标定误差目标：重投影 <0.5px；1m 处深度误差 <2cm；桌面平面拟合 <5mm。

**在线自标定（可选，P12）**：

- 用腕部相机 + 已知 EE 运动做 hand-eye `AX=XB`；用头部双目做立体自标定。
- 在 episode 开始时做 1–2s 安全小运动（不碰物体）；或用前几个任务动作在线估计。
- 只在标定置信度高时启用；否则用离线标定 + 保守阈值。
- 风险：180s 预算、动作规律性、评测端是否允许“预热动作”；默认不做，作为 debug 槽实验。

### 4.3 异步记忆与延迟预算

```text
Thread A (policy):  get_action(obs) → VLA + P-Action + P-Monitor → action chunk
Thread B (memory):  latest head stereo/wrist → P-SLAM Lite → SceneMemory
Shared:             double-buffer / lock-free; timestamp + confidence
```

| 组件 | 延迟目标 | 频率 | 备注 |
|---|---:|---|---|
| P-Monitor L0 | <1ms | 每步 | CPU |
| P-Monitor L1 | <5ms | 每步 | 小头/GPU batch |
| P-Action compose | <1ms | 每 chunk | 确定性 |
| P-SLAM stereo SGBM | 20–60ms | 5–10Hz | 320×240；可 ROI |
| P-SLAM feature/PnP | 5–20ms | 关键帧 | ORB/AKAZE |
| P-SLAM cluster/plane | 5–15ms | 关键帧 | 降采样 |
| VLA forward | p50/p95/p99 监控 | 每 chunk | 必须 < chunk 时长 |
| SURE-BT | <1ms | chunk 边界 | 确定性 |

**规则**：

- P-SLAM 永远不阻塞 `get_action`；读最新记忆；过期 >500ms 用 last-known/fallback。
- 如果 p99 超 chunk：降 P-SLAM 频率、降分辨率、减 ROI、或关闭 P-SLAM。
- 如果 jitter 增加 >10%：关闭 P-SLAM 的同步路径，只保留异步/关键帧。
- 官方 §6 记录延迟/波动/动作规律性；宁可少用，不要抖动。

### 4.4 N 端口 / reset / token

- N 个连续端口 8765..8765+N−1；每端口独立 policy 实例/状态。
- 共享后端时：请求分发 + 并发 + **每端口 state isolation**；不能全局单例。
- `reset()` 清空：SceneMemory、P-Monitor CUSUM、P-Action 锚、AEH horizon、VFCS cache、BT 信念。
- token：`metadata.token` + 每次 `meta.token`；双处一致。
- 断线/超时：指数退避重连；不要让一个端口拖垮其他端口。
- 4h soak：N 端口并发、内存泄漏、p99、reset 隔离。

### 4.5 动作规律性与 fallback

- P-Action 的相对合成可能产生 chunk 间不连续；用上一块末动作做 continuity check + 低通/限幅。
- P-SLAM 的修正不要直接改 VLA 动作；通过 BT waypoint/目标位姿修正，避免动作抖动。
- P-Monitor 只在关键状态干预；其他时候 log-only。
- fallback 链：`P-SLAM → BT waypoint → base VLA`；`P-Action → absolute head`；`P-Monitor → log-only`。
- 监控：p50/p95/p99、latency IQR、jerk、高频能量、离群率、chunk 间不连续、timeout。

### 4.6 部署检查单

| 项 | 检查 |
|---|---|
| 端口 | N 个连续端口可达；每端口独立 |
| token | metadata + meta.token 双校验 |
| reset | 清空所有状态；跨 episode 不泄漏 |
| 观测 | 只请求需要的 key；头部双目同分辨率 |
| 动作 | 形状/ dtype/ chunk 正确；joint/ee 互斥 |
| 延迟 | p99 < chunk；jitter <10%；4h soak |
| 内存 | P-SLAM <100MB；无泄漏 |
| 日志 | 每步延迟/动作统计/事件；可回放 |
| 安全 | 限幅/工作空间/不可逆任务 hold |
| 合规 | 单 checkpoint；无外部模型/数据；披露几何模块 |

## 5. 训练配方

### 5.1 损失

```text
L = L_flow
  + λ_a  * L_anchor          # P-Action 相对动作 + 绝对正则
  + λ_eq * L_equivariance    # 锚扰动一致性
  + λ_m  * L_dyn             # P-Monitor 动力学
  + λ_c  * L_contrast        # 本体状态对比（可选，RS-CL 风格）
  + λ_p  * L_para            # R3 复述一致性
  + λ_r  * L_recover         # R3 扰动/恢复
```

建议初值：

```text

λ_c = 0.05–0.1
λ_p = 0.1–0.3
λ_r = 0.1–0.3
```

## 6. 评测协议 DGS-32+

### 6.1 设计原则

1. **四重留出**：session（域）、paraphrase（语言）、perturbation（恢复）、state（物体/接触）。
2. **配对**：同一组 320 条件跑所有变体，报告配对差值。
3. **分层**：按任务/轴/难度/刚性 vs 变形物体分层。
4. **审计**：shortcut、显著性、渐进过拟合、数据源依赖、seeded 榜单。
5. **可证伪**：预注册 +5pp；CI 跨 0 不上线。
6. **不冒充官方**：DGS-32+ 是本地代理，不是官方榜单。

### 6.2 切分

| 留出 | 构造 | 度量 | 对应官方轴 |
|---|---|---|---|
| Held-out-session | 按 session 分组 5 折/留一 | in-domain vs held-out gap | 背景/位置/干扰物（代理） |
| Held-out-paraphrase | 每任务留 1 条复述 | canonical vs held-out gap | 未见物品/语言（代理） |
| Held-out-perturbation | 留 human_1 或 human_4 一条 | clean vs perturbed gap | 人扰 |
| **Held-out-state** | 物体中途移动/遮挡/拿走/追加；相机标定/裁剪扰动 | state gap / 重定位 | 位置/干扰物/人扰 |
| In-domain | 随机 episode 切分 | 拟合上限 | 对照 |

**构造方法**：

- **离线**：用物体 mask/编辑做 2D 移动/遮挡；用 crop/warp 模拟相机标定；用动作/状态扰动模拟 slip；用 simple tabletop sim（PyBullet）做 3D 物体移动。
- **真机**：调试槽按 human_1/human_4 备注移动物体；低摩擦物体/轻推做 slip；不碰不可逆任务。
- **不要**把备注当测试泄漏；训练用 human_1，测试用 human_4（或交换），并标注 inferred。

### 6.3 指标

| 指标 | 定义 | 用途 |
|---|---|---|
| Success | 全步骤完成率 | 主指标 |
| Step score | 官方加权部分分 | tie-break/诊断 |
| Axis success | 每轴 64 次 | 分轴诊断 |
| Recovery rate | 扰动后恢复并完成的比例 | 恢复能力 |
| Time-to-recovery | 扰动到恢复完成的时长 | 恢复效率 |
| **Slip AUROC/AP** | P-Monitor 对 slip 的检测 | P-Monitor |
| **False completion rate** | 未完成但报完成的比例 | P-Monitor/P-SLAM |
| **Re-localization success** | 人移动后重新找到目标的比例 | P-SLAM |
| **Time-to-relocalize** | 从丢失到重新定位的时长 | P-SLAM |
| **Object pose error** | 目标位姿误差（cm/deg） | P-SLAM |
| Anchor drift | 相对动作锚的漂移 | P-Action |
| Calibration error | 双目/手眼重投影/深度误差 | 标定 |
| p99 latency | `get_action` 延迟 | chunk 合同 |
| Jitter | 动作 jerk/高频能量 | §6 可信度 |
| Timeout rate | 超时比例 | 失败模式 |

### 6.4 统计

- **二项 CI**：Wilson 95%；320 次、p≈0.3 时 ±5.0pp；SE≈2.56pp。
- **单任务**：10 次，SE≈14.5pp；不要因单任务 +10pp 下结论。
- **单轴**：64 次，SE≈5.7pp；分轴结论要谨慎。
- **配对**：同一条件 A/B；McNemar；差值 SE≈sqrt(d/320)；d=0.15 → 2.17pp。
- **分层 bootstrap**：按 task/session 重采样；报告 95% CI。
- **预注册**：目标 +5pp；MDE 计算；不要事后改目标。
- **多重比较**：Holm/BH；轴级/任务级分开。
- **序列检验**：若早停，用 alpha spending；不要偷看多次。
- **报告**：均值 + CI + 配对差值 + 失败模式分布；不只报一个数。

### 6.5 消融

- 动作：绝对 vs 相对 vs 双头；锚扰动 on/off；EE vs joint。
- 本体：单帧 vs H=4/8/16；VLM prefix vs action head；对比正则 on/off。
- P-Monitor：L0 vs L1 vs L2；阈值；CUSUM；相位分层；log-only vs 干预。
- P-SLAM：双目 vs 单目；物体记忆 on/off；重定位 on/off；关键帧频率；桌面平面先验 on/off。
- P-SLAM Full：几何 token 数；位姿加噪；token dropout；LoRA vs 全参。
- 运行时：SURE-BT on/off；AEH on/off；VFCS K=1/2/4；异步 vs 同步。
- 数据：R3 各组件 on/off；clean:perturbed 比例；session 采样。
- 评测：DGS-32+ 各留出；seeded 榜单审计。

### 6.6 审计

| 失效模式 | 诊断 | 在 UniBot 上的做法 | 如果失败 |
|---|---|---|---|
| Shortcut solvability | 场景-only 小模型 vs 语言条件模型 | 0.09B/ResNet-18 probe，无语言；held-out session | 若 gap 小，语言投入降级 |
| Lack of statistical significance | 配对检验/CI | 320 次配对；McNemar；预注册 +5pp | 不显著 → 不上线 |
| Creeping overfitting | 留出 session/复述/扰动/状态 | 不调 held-out；限制提交次数 | 若 held-out 掉，回退 |
| Data-source dependence | 按 robot/date 留出 | 2–6 robot ID/5 个月日期做 leave-one-robot/date-out | 若 gap 大，Regroup 加权 |
| **Seeded leaderboard** | 反推条件成功率 | 2 步任务 61.5% 常数；`generated_at=null` | 不拿榜单做模型选择 |

## 8. 创新点清单

> 状态：押注=主线；高优先=强烈建议；试验=可选；支撑=评测/工程；降级=保留但非主回路；砍=不做。

### I1 PSALM：本体感知场景锚 + 物体级 SLAM 记忆（押注｜新）

- **动机**：官方 5 轴里 4 轴是 3D 物体状态变化；R3-VLA 只有不变性、没有状态；API 无深度但头部双目可用；本体感知高频、域不变。
- **与现有方案的差异**：不是“更大的 VLA”，也不是“全视频 world model”；是 **VLA + 确定性几何 + 本体动力学** 的混合体。P-Action 改动作表示，P-Monitor 改运行时可靠性，P-SLAM 改场景状态；三者共享一个 checkpoint。
- **技术可行性**：P-Action/P-Monitor 只需官方数据；P-SLAM Lite 用 OpenCV/PCL 经典几何；双目 320×240 在 CPU/GPU 可实时；异步不阻塞 `get_action`。
- **所需资源**：1–2 人 ×6 周；1–2×A100（LoRA）或 8×H100（全参）；1 个调试槽/周；官方 33k；无外部数据。
- **落地步骤**：数据审计/标定 → P-Action → P-Monitor → P-SLAM Lite → BT 集成 → DGS-32+ → 调试槽 → 提交。
- **风险**：单模型合规（几何算不算模型）；双目标定/透明物体；P-SLAM 延迟；P-Monitor 误报；没有调试槽。
- **状态**：主线。

#### I1a P-Action：本体锚定相对动作（押注｜新）

- **动机**：绝对 EE/joint 动作把 rig 坐标写死；真机底座/相机/桌面差异导致偏移；chunk 内误差累积。
- **差异**：预测 `Δξ/Δq`，用实测 `s_t` 合成绝对动作；双头 + anchor perturbation；chunk 内 star parameterization。
- **可行性**：官方动作可直接转相对；服务端确定性合成；不改 API 形状；LoRA 3–5 天。
- **资源**：官方 33k；1×A100；3–5 天；无需新传感器。
- **步骤**：转换/校验 → 相对头 → 双头/一致性 → 离线 held-out session → API 合成 → 调试槽。
- **风险**：锚噪声；关节/EE 尺度；chunk 不连续；与绝对头冲突。
- **状态**：主线（最便宜，先做）。

#### I1b P-Monitor：本体动力学残差（押注｜新）

- **动机**：无触觉/力；视觉被遮挡；抓滑/碰撞/卡住/人扰需要在线检测；false completion。
- **差异**：用 `(s_t,a_t,s_{t+1})` 自监督残差；L0 零模型、L1 同 checkpoint 辅助头；CUSUM/EVT/conformal；只触发 verify/careful。
- **可行性**：数据现成；L0 CPU <1ms；L1 小头；无需新标签。
- **资源**：官方 33k；1×A100 或 CPU；1–2 天；无新传感器。
- **步骤**：L0 log-only → 阈值校准 → L1 → 相位分层 → BT/AEH 集成 → 调试槽。
- **风险**：预期接触误报；分布漂移；阈值过保守/过激进；官方 §6 抖动。
- **状态**：主线（最便宜，先做）。

#### I1c P-SLAM Lite：桌面物体位姿记忆（高优先｜新）

- **动机**：人移动物体/遮挡后策略无记忆；位置/干扰物/背景/未见物品/人扰五轴；API 无深度但头部双目可用。
- **差异**：object-level local SLAM，不是全图 SLAM；桌面子地图 + 物体簇 + 抓取约束 + 重定位；经典几何，无学习权重；输出给 BT/waypoint。
- **可行性**：OpenCV SGBM/ORB/PnP + PCL 聚类；320×240 5–10Hz；异步；刚性物体约 18–20 任务。
- **资源**：官方 33k + 双目标定；1×A100/4090 或 CPU；1–2 周；1 个调试槽。
- **步骤**：标定 → 桌面平面/聚类 → 物体记忆 → 跟踪/抓取约束 → 重定位 → BT 集成 → 调试槽。
- **风险**：透明/反光/无纹理；标定误差；遮挡；延迟；重定位误匹配；单模型合规。
- **状态**：高优先（第二级；P-Action/P-Monitor 之后）。

#### I1d P-SLAM Full：几何 token 进 VLA（试验｜新）

- **动机**：Lite 只给 BT；如果 VLA 能直接“看到”物体位姿，插入/放置可能更准。
- **差异**：8–16 个 geometry token，state-guided；同 checkpoint；训练时位姿加噪/丢 token。
- **可行性**：参考 GeoAlign；需要几何编码器/LoRA；只做 2–4 个几何关键任务。
- **资源**：4–8×H100；1–2 周；官方 33k + 几何标注/弱监督。
- **步骤**：几何 token → 加噪训练 → 几何关键任务 → 消融 → 合规审计。
- **风险**：单模型审计；过拟合完美位姿；延迟；收益不确定。
- **状态**：试验（Lite 门控通过后再做）。

### I2 R3-VLA：Regroup/Rephrase/Recover（保留｜训练骨架）

- **动机**：session 域偏移、5 复述、60 条人扰备注是免费监督；R3 已在第 9 轮论证。
- **差异**：本轮不重复；作为 PSALM 的训练底座；P-Action/P-Monitor 与 R3 共享 checkpoint。
- **可行性**：第 9 轮已设计；数据现成；LoRA/全参。
- **资源**：1–8 GPU；6 周；官方 33k。
- **步骤**：沿用第 9 轮 Stage 0–3；本轮加 P-Action/P-Monitor 损失。
- **风险**：session 混杂；复述覆盖不足；备注过拟合。
- **状态**：保留（训练骨架）。

### I3 SURE-BT + AEH + VFCS（保留/升级｜运行时骨架）

- **动机**：固定 chunk 开环；BT 在 chunk 边界验证/恢复；AEH 可靠前缀；VFCS 关键状态选块。
- **差异**：新增 P-Monitor 残差截断、P-SLAM 事件谓词、false-completion 复核；不改变 API chunk 合同。
- **可行性**：确定性代码；已有第 8 轮基础；1–2 人 ×2 周。
- **资源**：CPU；1–2 人 ×2 周；日志/监控。
- **步骤**：谓词接线 → AEH 残差 → VFCS tie-break → 延迟/抖动 profiling → 调试槽。
- **风险**：谓词误报；AEH 误判；VFCS 延迟/抖动；过约束。
- **状态**：保留/升级（运行时）。

### I4 DGS-32+：四重留出评测 + 审计（支撑｜升级）

- **动机**：官方轴隐藏；随机切分泄漏；seeded 榜单不可信；需要状态/接触/几何指标。
- **差异**：session/复述/扰动/状态四重留出；配对/分层/CI；seeded 榜单审计；slip/relocalization 指标。
- **可行性**：1 人 ×2 周；本地数据；离线编辑/回放 + 调试槽。
- **资源**：1×A100/4090；2 周；官方 33k。
- **步骤**：切分 → 320 矩阵 → 状态扰动 → 指标 → 统计 → 审计。
- **风险**：代理效度；sim-to-real；小样本；离线编辑不真实。
- **状态**：支撑（可作为对外贡献）。

### I5 Stereo perception：把头部双目用起来（支撑｜新）

- **动机**：API 无深度；头部左右是立体对；StereoPolicy/ExStereo 证明双目收益。
- **差异**：不建全 SLAM；至少做 stereo depth/feature/geometry token；作为 P-SLAM 的输入。
- **可行性**：经典 SGBM 或轻量 stereo encoder；320×240；5–10Hz。
- **资源**：1×A100；3–5 天；官方 33k。
- **步骤**：标定 → SGBM → 深度质量评估 → 作为 P-SLAM 输入/策略辅助。
- **风险**：标定；透明/反光；延迟；与 2D VLA 融合。
- **状态**：支撑（P-SLAM 的基础）。

### I6 Memory-guided search：记忆引导搜索（高优先｜新）

- **动机**：人把物体移出视野/遮挡后，策略需要“找回来”，而不是原地重试。
- **差异**：用 last-known pose + 不确定性采样视角；VLA/BT 执行搜索；找到后更新记忆。
- **可行性**：P-SLAM Lite 的扩展；头部/腕部/小臂微动；无需新模型。
- **资源**：CPU/GPU；1 周；调试槽。
- **步骤**：last-known → 视角采样 → 特征匹配 → 失败 fallback → BT 搜索。
- **风险**：搜索时间；不可逆任务；误匹配；180s 预算。
- **状态**：高优先（P-SLAM 的一部分）。

### I7 False-completion check：完成前复核（高优先｜新）

- **动机**：ReViP 的 false completion；视觉被遮挡时策略可能“以为完成”；官方步骤分/成功率都受影响。
- **差异**：VLA 报完成后，用 P-SLAM 目标位姿 + 腕部视觉 + 本体残差做一次复核；不直接相信语言/状态。
- **可行性**：BT 叶子；P-SLAM 输出；1 周。
- **资源**：CPU；1 周；调试槽。
- **步骤**：完成谓词 → 目标位姿检查 → 腕部检查 → 失败则继续/恢复。
- **风险**：复核误判；额外时间；不可逆任务。
- **状态**：高优先（P-Monitor/P-SLAM 的组合）。

### I8 Test-time self-calibration：测试时自标定（试验｜新）

- **动机**：官方评测 rig 可能与数据不同；双目/手眼标定误差直接影响 P-SLAM。
- **差异**：用腕部相机 + 已知 EE 运动做 hand-eye `AX=XB`；用头部双目做立体自标定；episode 开始 1–2s 安全小运动或在线估计。
- **可行性**：经典几何；CPU；1 周；需要安全动作。
- **资源**：CPU/GPU；1 周；调试槽。
- **步骤**：标定动作 → 特征跟踪 → 解 `AX=XB` → 置信度 → fallback。
- **风险**：180s 预算；动作规律性；评测端限制；标定失败。
- **状态**：试验（P12；默认离线标定）。

### I9 Language/paraphrase：5 条复述 + canonicalization（保留）

- **动机**：5 条官方复述；LIBERO-Para 22–52pp；未见物品/语言轴。
- **差异**：R3 Rephrase；本轮不重复；与 P-SLAM 的目标选择共享语言特征。
- **可行性**：数据现成；规则增广；1 人 ×3–5 天。
- **资源**：1×A100；3–5 天；官方 33k。
- **步骤**：dropout/一致性 → 留一复述 → canonicalization → 目标选择。
- **风险**：评测复述不在 5 条内；marginalization 延迟；一致性伤 canonical。
- **状态**：保留。

### I10 Placement anchor：放置锚点/位姿迁移（保留｜叶子）

- **动机**：终局放置仍是成功闸门；锚点/相对位姿提精度。
- **差异**：不做主架构；作为 BT `Act(place)` 叶子/目标提供器；与 P-SLAM 目标位姿结合。
- **可行性**：沿用第 7 轮；几何/锚点；无需新模型。
- **资源**：1 人 ×1 周；沿用代码。
- **步骤**：锚点提供器 → BT 叶子 → 终局验证。
- **风险**：锚点误差；透明/反光；与恢复冲突。

### I11 Deployment/action regularity：部署与动作规律性（工程｜保留）

- **动机**：N 端口/状态隔离/token/延迟/§6 是硬门槛；P-SLAM 不能造成抖动。
- **差异**：不是研究点；是部署检查单 + 监控。
- **可行性**：工程；1 人 ×1 周。
- **资源**：N 端口/4h soak；无额外 GPU。
- **步骤**：端口 → 隔离 → token → 缩放 → 异步 → soak → 日志。
- **风险**：并发/内存泄漏/断线；p99；jitter。
- **状态**：工程（必做）。

### I12 Whole-body pivot：全身 pivot/腰腿（降级/砍｜新负面结果）

- **动机**：G1 是人形，理论上可以用腰腿/底座扩大工作空间。

- **可行性**：低；数据没有覆盖；真机安全风险。
- **资源**：不值得投入。
- **步骤**：不做；如果要做，先做 1 个任务的 pivot 可行性实验。
- **风险**：移动底座/腰腿可能被评测端视为异常/不安全；动作规律性。
- **状态**：砍（本轮明确修剪）。

### I13 External VLM task-stage observer（砍）

- **动机**：ReViP 用外部 VLM 做任务阶段观察，降低 false completion。
- **差异/问题**：单模型合规风险；外部依赖/延迟；官方 API 只给观测，不给外部模型。
- **可行性**：低（合规）。
- **资源**：不值得。
- **步骤**：不做；用 P-Monitor + P-SLAM 的视觉/本体复核替代。
- **风险**：合规/延迟/可复现性。
- **状态**：砍。

### I14 Full learned world model（砍/降级）

- **动机**：DreamZero 等 world model 在榜单上出现；视频预测可能帮助规划。
- **差异/问题**：6B + 实时 + 单模型 + 无深度；视频 world model 资源/延迟/复合误差不划算。
- **可行性**：低（本轮资源）。
- **资源**：8×H100+；数周；大量视频。
- **步骤**：不做；用 P-Monitor（低维动力学）+ P-SLAM（几何世界模型）替代。
- **风险**：资源/延迟/合规。
- **状态**：砍（保留为远期）。

### I15 Per-task LoRA / full digital twin（砍）

- **动机**：每任务适配/全 32 任务孪生看似能提分。
- **差异/问题**：单模型赛道不允许按任务混用多个模型；全孪生资源巨大；官方数据已够。
- **可行性**：低。
- **资源**：不值得。
- **步骤**：不做；用 R3 的统一模型 + 任务条件。
- **风险**：合规/资源/过拟合。
- **状态**：砍。

## 9. 风险、合规与开关

| 风险 | 概率 | 影响 | 缓解 | 停止条件 |
|---|---|---|---|---|
| 双目标定/同步不准 | 中 | 高 | 离线标定 + 在线自标定 + 置信度 fallback | 重定位 <70% → 关闭 P-SLAM |
| 透明/反光/无纹理 | 高 | 中 | 腕部 servoing + P-Monitor fallback；只做刚性纹理物体 | 失败率高 → 缩小范围 |
| 遮挡/丢失 | 高 | 中 | 记忆 + 搜索 + 多视角 | 搜索超时 → 放弃该子任务 |
| P-SLAM 延迟/抖动 | 中 | 高 | 异步、关键帧、降分辨率、ROI | p99 超 chunk 或 jitter >10% → 关闭 |

## 12. 一句话押注

**把本体感知从单帧条件升级为“相对动作锚 + 自监督动力学残差监测器”，再用头部双目 + 腕部相机维护桌面级物体位姿记忆，在人物移动/遮挡后重新定位目标；先做 P-Action + P-Monitor（1–2 周、零新数据），P-SLAM Lite 作为第二级，完整因子图只在标定/延迟/单模型合规门控通过后上——这是本轮最值得押注的方向。**
