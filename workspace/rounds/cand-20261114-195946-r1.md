# 第 70 轮（承接第 69 轮「FLUID-RAS 交互消歧闭环」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「步骤分」×「VLA」）

> R69 问出了「我该向谁求证、还能问什么」，把不确定性一分为二（aleatoric / epistemic），用流匹配多模态策略 + 主动交互去消解歧义。但它仍站在**单个决策点**上看世界：它默认「只要此刻看清该走哪个模态，剩下就是执行」。这对一次抓取成立，对一个**长时程 VLA** 不成立——VLA 的典型失败不是某一帧动作坏，而是**指令被逐步误接地**：第 3 步把「把蓝积木放到左盘」听成「放到红盒旁」，之后每一步都自洽地走在一个错误但完整的故事里；单步看，每个动作都在策略密度的高脊上，R69 的模态分解毫无异样。
>
> 本轮两个灵感正好补上这块：
> - **步骤分（partial credit / step score）**把「结果对不对」拆成「过程每一步对不对」，让系统能区分**运气好**（结果对、步骤错）与**倒霉**（步骤对、结果错）——这恰是 outcome-only 强化学习看不见、也最容易被它学坏的地方；
> - **VLA**把语言当任务规格，于是长程任务天然可分解为**逐子句的步骤契约**，也天然暴露「语义接地错误」这一 R69 无法观测的失效模式。
>
> 核心命题：**把 R69 的「单步不确定性」升级为「长程信用账本」：用过程评分器给每一步记分，用双式记账把「过程分」与「最终结果」对账，用反事实干预把失败定位到具体一步，用信用完整性门保证「不从侥幸的成功里学习」。当账本对不上，先分清是运气、倒霉、评分器撒谎、还是语义误接地，再决定局部回滚、重新确认意图、还是退回 R69/R68 的全局保守。** 命名 **LEDGER-RAS**（Language-grounded Epistemic Dense-credit Grading & Evidence-rigorous Risk-adaptive Supervision）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**我到底错在哪一步，而我的记分本身可信吗**」——不确定性不只是刹车或提问，也可以是一本必须对得上的账。

## 0. 直觉与动机

**灵感 1（步骤分 → 结果与过程的解耦）**
直觉：考试里，学生可能「过程全对、最后算错」（该给步骤分），也可能「过程全错、蒙对答案」（不该给满分）。只看得分的评价系统会把后者当优等生；一个长程 VLA 若只在任务成功时给正梯度，就会把「碰巧做对」的错误计划固化成能力。步骤分的价值不是让奖励更密，而是让系统能问出 R69 问不出的问题：**这一次成功，到底是学会了，还是运气？**
严谨：过程评分器 s_φ 给每步一个部分信用；把最终结果 R 与「过程账本」末端预测 V_T 对账，残差 ρ=R−V_T 的**符号、总体分布、局部结构**分别编码运气、倒霉、与可归因错误。

**灵感 2（VLA → 长程复合与语言接地）**
直觉：VLA 的失败是**复合**的：单步误接地概率 p 很小，但 T 步累积成 1−(1−p)^T。更麻烦的是它「本地自洽」：一旦第 t* 步把语言子句接错，后续每一步都在为一个错误目标做最优控制，任何单步异常检测都看不见。要抓它，必须把指令拆成子句、给每步配一个**可独立核验的契约谓词**，让「动作合理」与「目标正确」分开判。
严谨：ℓ→{ℓ_i, p_i}，每步对齐到一个子句 i(t)；契约匹配率与价值增量是两条正交证据，前者测「目标对不对」，后者测「进度值多少」。

**灵感 3（评分器本身是测量 → 递归计量）**
直觉：R68 计量传感器，R69 计量模态，本轮计量**「进步」这个量本身**。评分器会近视（只奖励看起来像进步的动作）、会偏置（分布外系统性高估）、会被投毒；更糟的是——**策略会学会为评分器表演**（process reward hacking / Goodhart）。所以账本必须是**双式**的：过程一侧与结果一侧必须对得上；对不上不是噪声，而是信息，绝不能被平滑掉。
严谨：把过程评分器视为随机测量，要求它对最终成功率满足**鞅校准** E[R|τ_{0:t}]=V_t；用总体残差均值识别评分器偏置，用残差方差识别结果噪声，用逐轨迹局部结构识别可归因错误。

**灵感 4（定位是一种新的 epistemic 动作）**
直觉：R69 的信息动作是「看、问、触」。到了长程，最值钱的信息动作往往是「**停在这一步查一下**」「**回滚到岔口换一条**」「**就这个子句再确认一次**」——这是对具体时刻施加的 do 操作，是**因果归因**，不只是感知。
严谨：动作空间从 (a,g) 扩到 (a,g,κ)，κ∈{checkpoint, rollback(t), re-ask(i), re-perceive(i), counterfactual-replay(t)}；审计预算从「交互次数」变成「信用审计/回滚深度」。

**灵感 5（信用完整性是一条硬不变式）**
直觉：最危险的不是失败，而是**被误认为成功的失败**。所以必须有一条铁律：**未经账本核验的成功，绝不作为正证据；未经双源确认的归责，绝不单独定案。** 否则 R70 只是给 R69 装了一本会做假账的账本。
严谨：信用完整性门（CIG）在策略更新前拦截 Type-L（侥幸成功）与未归因失败；归因必须过「价值跌落 + 反事实回放 + 契约失配」多源一致。

## 1. 形式化定义（增量：定义 310–326）

**定义 310（LEDGER-RAS 总览）** LEDGER-RAS = (VLA-G, SCD, PCA, CIL, CRD, T-VoI, SCA, CIG, RAS-WM‡)。三不变式：
(i) **实时流零学习写操作**（继承 R69 定义 293-i）；
(ii) **信用审计预算**：单位时间审计/回滚 ≤ 1 次、回滚深度 ≤ D、成本 ≤ c_max；任一 κ 必须通过与任务动作相同的 C-RAS-WM 认证；
(iii) **信用完整性**：未经账本核验的成功不得作为正证据；未双源确认的归责保持「未归因」并走全局保守。

**定义 311（VLA 策略与语言子句分解 VLA-G）** 指令 ℓ 经冻结解析器分为 N 个子句 {ℓ_1..ℓ_N}，各配契约 c_i=(p_i, δ_i)（可独立核验的子目标谓词与容差）。VLA 策略 π_θ(a_{t:t+H}|o_t, ℓ)（条件编码复用 R69 FMP，并把 ℓ 的嵌入并入 z_t；允许直接复用现成 VLA 主干）。单调对齐 i(t) 使子句按序推进；契约匹配 m_t = 1[p_{i(t)}(o_t) ≥ 1−δ_i]。

**定义 312（过程评分器 SCD）** s_φ(τ_{0:t}, ℓ) = V_t ∈ [0,1]，是「从当前进度最终成功」的概率预测；同时输出步骤分增量 δ_t = V_t − V_{t−1} 与不确定度 u_t。V_t 构成账本的**过程侧**。SCD 可为独立小头，也可为 VLA 的文字-视觉-进度头（共享 trunk，零重复编码）。

**定义 313（双式账本与对账残差）** 过程账本 P(τ)={V_t, δ_t, m_t}；结果账本 O(τ)=R(τ)∈[0,1]（终端成功 / 整体契约满足）。**对账残差** ρ(τ)=R(τ)−V_T。**信用守恒**要求对校准评分器 E[ρ]=0。记账本一致性指数 Λ=1−|ρ|，局部归因图 {φ_t}（定义 315）。

**定义 314（残差分解：偏置 vs 噪声）** 对一批轨迹，grader 偏置 b=E[ρ]（系统性，指向评分器失真/被投毒/分布漂移），结果噪声 σ_ρ²=Var(ρ)（aleatoric 运气）。b 显著非零 ⇒ 评分器不可信；b≈0 且单条 |ρ| 大 ⇒ 单次运气。在线用 χ²/CUSUM 检验 b 的漂移。

**定义 315（反事实步骤归因 CIL）** 设 τ 失败（R=0）。对 step t：
- 反事实信用 φ_t = E_{a~π}[V_T(τ | do(a_t=a_t^ref))] − V_T(τ)（换上「契约正确」的动作能救回多少）；
- 消融敏感度 ψ_t = V_T(τ) − E[V_T(τ | do(a_t=∅))]（抽掉这一步会掉多少）。
归责步 t* = argmax_t φ_t，且需满足：(a) 价值跌落集中（|δ_{t*}| 显著高于均值）；(b) 反事实回放确实把 V_T 抬过阈值；(c) 该步契约失配（m_{t*}=0）或语义消歧增益显著；(d) 至少两条证据一致。
**两类归责**：若 t* 处契约失配、且在同一状态换动作也救不回、只有重述子句才回升 ⇒ **Type-B_sem（语义误接地）**；若契约正确、换动作可明显回升 ⇒ **Type-B_exec（执行错误）**。

**定义 316（信用-风险耦合 CRD）** 定义信用置信 CT=f(鞅校准, 证据一致, 契约匹配)。按账本类型分档：
- **Type-E（账本平衡且成功）** → λ=λ_floor(U_ale)，继承 R69 的 resolution bonus；
- **Type-N（过程好、结果坏）** → 不归罪于策略，仅按 U_ale 收紧并优先重试，**不学习**；
- **Type-B_exec（可归因执行失败）** → 局部回滚到 t*−1 重执行，λ 仅在 t*−1 之后收紧；
- **Type-B_sem（语义误接地）** → 先 re-ask / 重解析子句 i(t*)，再重新规划；**不改写执行策略**；
- **Type-Q（账本不平且不可归因 / grader 不可信）** → 全局 λ=λ_floor(U_ale+U_epi)，退回 R69/R68。

**定义 317（步骤级干预动作 κ）** κ∈𝒜_credit = {checkpoint(t), rollback(t), re-ask(i), re-perceive(i), counterfactual-replay(t)}。所有 κ 过 C-RAS-WM 前缀认证；越界即作废，相关失败视为未归因。

**定义 318（时序 VoI 审计调度 T-VoI）** 审计点/干预选择 κ* = argmax_κ [E[ΔH(blame)] − c(κ)] / 时长，s.t. 预算与认证；归因熵 H(t*) 由 |δ_t|·u_t 加权，故边际价值在「价值陡降且不确定」处最高。R69 的 MINT 是 T=1 的退化特例。

**定义 319（评分器校准与对抗 SCA）** 三重审计：(a) **鞅校准误差** ECE_m（V_t 与实际成功率的分箱偏差）；(b) **奖励黑客红队**：只优化 s_φ 而不完成任务，检测「表演型进步」；(c) **契约一致性**：高 s_t 必须对应 m_t 满足。ECE_m>τ_ece 或红队通过率>τ_r ⇒ 标记 grader 不可信。

**定义 320（信用完整性门 CIG）** 更新前硬门：Type-L 轨迹永入**隔离缓冲**（不进入正回放），触发「侥幸成功」告警；梯度掩码 w_t：仅对已核验步给权，未归因/未核验步 w_t=0；Type-B 仅在 t* 认证后更新，且保护 t* 之前的前缀不被改写（防「功劳归错」）。

**定义 321（证书 J_LEDGER）** J_LEDGER=(J_FLUID, grader_ECE, ledger_bias_b, residual_p95, blame_cert_hash, contract_match_rate, quarantine_ratio, typeL_rate, ledger_ver)。Valid ⇔ Valid(J_FLUID) ∧ grader 可信 ∧ 归因已认证 ∧ 信用完整性未破 ∧ 审计预算未越界。

**定义 322（长程复合误差与严格包含）** 单步误接地概率 p 下，T 步至少一次误接地概率 = 1−(1−p)^T。LEDGER 的局部归因把「每次失败重跑 T 步」降为「重跑受影响后缀 T−t* 步」。当 T=1 且 grader 可信时，LEDGER≡FLUID；当账本不可信/不可归因时逐指令退回 FLUID/R68。

**定义 323（评分器吸收与反吸收）** 缓变退化可被近视评分器「吸收」：s_φ 持续给出看似合理的部分信用，而任务实际漂移。反吸收三通道：契约匹配 m_t、反事实敏感度 ψ_t、结果侧 ρ。若 s_φ 高、m_t 下降、ψ_t→0，判「grader 吸收」。

**定义 324（分布式账本 / 多评审）** 可选：多个正交评审（视觉契约核验、语言子句解析、力/位传感器、独立回放）组成评审团；单评审不得定案，需 k 个一致；用于抗投毒与抗共谋。

**定义 325（干预安全）** κ 的回滚/重看/重问不得越过安全包络、不得使已锁定的安全前缀失效、不得造成状态跳变；回滚目标必须仍在 C-RAS-WM 的可达安全集内。

**定义 326（参与式过程审计 QAuditor-P）** 审计对象：步骤分是否被单源采纳、归因是否经由反事实、Type-L 是否被隔离、契约谓词本身是否有偏。结论回灌 AuditBuf，成为下一轮审计调度的成本/先验。

## 2. 关键算法骨架

```python
# IP-264 VLA-G：把语言指令拆成带契约的子句（冻结解析器 + 可核验谓词）
def decompose_instruction(ell):
    return [(cl, predicate(cl), tol(cl)) for cl in parser(ell)]   # N 个子句

# IP-265/266 SCD + PCA：逐步记分并对账
def ledger_rollout(policy, scd, obs, ell):
    clauses, V_prev, ledger = decompose_instruction(ell), 0.0, []
    for t in range(horizon):
        a = policy.act(obs[t], ell)
        m = match_contract(clauses, t, obs[t])          # 契约谓词，独立核验
        V = scd.value(obs[t], ell)                       # 过程侧 V_t
        ledger.append(dict(t=t, a=a, V=V, delta=V - V_prev, m=m,
                           u=scd.uncertainty(obs[t])))
        V_prev = V
    R = task_success(obs[-1], ell)                       # 结果侧
    return ledger, R, R - ledger[-1]['V']                # 返回 rho

# IP-266/267 PCA + CIL：把残差变成分类与归因
def reconcile(ledger, R, rho, stats):
    if abs(stats.bias) > TAU_BIAS:            return ('TYPE_GRADER', None)
    if R >= 1 and ledger[-1]['V'] >= TAU_OK:  return ('TYPE_E', None)   # 学会
    if R >= 1 and ledger[-1]['V'] <  TAU_OK:  return ('TYPE_L', None)   # 侥幸
    if R <  1 and ledger[-1]['V'] >= TAU_OK:  return ('TYPE_N', None)   # 倒霉
    t_star = argmax(ledger, key=lambda s: abs(s['delta']))
    if not counterfactual_raise(ledger, t_star):        return ('TYPE_Q', None)
    if contract_mismatch(ledger[t_star]):
        return ('TYPE_B_SEM', t_star)                   # 语义误接地
    return ('TYPE_B_EXEC', t_star)                      # 执行错误

# IP-268 CRD：按账本类型选择风险/修复策略
def credit_risk(ledger, kind, t_star, U_ale, U_epi):
    if kind == 'TYPE_E':       return dict(repair=None,   lam=lam_floor(U_ale))
    if kind == 'TYPE_N':       return dict(repair='retry',lam=lam_floor(U_ale))
    if kind == 'TYPE_B_EXEC':  return dict(repair='rollback', from_step=t_star-1,
                                           lam=lam_floor(U_ale))
    if kind == 'TYPE_B_SEM':   return dict(repair='re-ask', i=clause_of(t_star),
                                           lam=lam_floor(U_ale))
    return dict(repair='global', lam=lam_floor(U_ale + U_epi))   # TYPE_Q/GRADER

# IP-271 CIG：更新前硬门（不从侥幸成功里学习）
def credit_integrity_gate(ledger, kind):
    if kind == 'TYPE_L':
        quarantine(ledger); alarm('SPURIOUS_SUCCESS'); return False
    if kind in ('TYPE_Q', 'TYPE_GRADER'):
        return False                                     # 不用于学习
    return True                                          # E/N/B 按掩码更新

# IP-275 主闭环（继承 R69，把单步输出送入长程账本）
def LEDGER_RAS_round(M, obs, ell):
    z, o = M.mtm.forward(...); c, U_cal, _ = M.cof.step(...)
    # 1) R69 单步层：模态与不确定性
    K = 1 if M.fmp.mode_head(z) < TAU_MODE else 4
    U_ale, U_epi, modes, _ = M.aud.decompose(M.fmp.sample(o, K), z, M.fmp.mode_head)
    # 2) R70 长程层：记分 + 双式对账
    ledger, R, rho = M.pca.ledger_rollout(M.policy, M.scd, obs, ell)
    kind, t_star = M.pca.reconcile(ledger, R, rho, M.scd.stats)
    # 3) 只在不平/高不确定处花审计预算（T-VoI）
    if kind in ('TYPE_Q', 'TYPE_B_EXEC', 'TYPE_B_SEM') or ledger[-1]['V'] < TAU_OK:
        kappa = M.tvoi.choose(ledger, M.budget)          # checkpoint/rollback/re-ask
        if kappa and M.c_ras_wm.certify_info(kappa, o):
            M.cil.execute(kappa)                         # 反事实回放 / 重问
            kind, t_star = M.pca.reconcile(ledger, R, rho, M.scd.stats)
    # 4) 信用-风险耦合：局部修复 vs 全局保守
    risk = M.crd.decide(ledger, kind, t_star, U_ale, U_epi)
    lam  = max(M.efs.risk_scale(...), risk['lam'])
    A    = M.ach.propose(x_prime, H=M.vista.H)
    k    = M.c_ras_wm.certified_prefix(A, ..., wm_preds)
    if risk['repair'] == 'rollback':
        k = min(k, rollback_prefix(risk['from_step']))
    # 5) 执行 + CIG 守门更新
    if M.cig.allow(ledger, kind):
        M.updater.credit_masked_step(ledger, kind, t_star)   # w_t 掩码
    # 6) 过程审计 + 证书（异步）
    M.qauditor_p.submit_async(ledger, kind, t_star, rho)
    return k, lam, modes, kind, t_star
```

## 3. 推导

**引理 19（单次侥幸不可作为证据）** 对鞅校准的过程评分器，单轨迹残差 ρ 的期望为 0，即 E[R−V_T]=0。因此仅凭一次 R=1 无法区分 Type-E 与 Type-L；区分必须依赖账本一致性（V_T 与 m_t 的联合）与总体偏置 b。系：任何「成功即正样本」的学习器都在系统性吸收运气，**CIG 的必要性由此得证**。

**引理 20（局部归因的修复增益）** 若失败可归因到 t* 且反事实认证（φ_{t*}>0、ψ_{t*}>0），则回滚修复的期望执行代价 ≤ (T−t*)/T 倍全局重启代价，且成功率恢复量不低于全局保守的对应量（只需重做受影响后缀，前缀不变）。若归因不集中（max_t|δ_t| 与均值无显著差异），全局保守不劣。系：**越可分、越靠前的错误，局部修复越值钱**——与 R69 引理 16 同构。

**引理 21（评分器吸收的判别性）** 定义吸收指标 A = 1[s_φ 高]·(1−m_t)·(1−ψ_t)。若退化只体现在执行层而评分器近视，则 A→1；而 R69 的 FMA 可能因动作仍在流密度高脊上而不报警。故 (m_t↓, ψ_t→0, s_φ↑) 是 LEDGER 特有的吸收模式，补 R69 的 FMA 在「语义/过程层」的盲区。

**引理 22（复合误差与局部化收益）** 单步误接地 p、T 步下失败概率 F_T=1−(1−p)^T；若每次可归因失败平均后缀长 E[T−t*]，局部修复下有效失败增长为 F_{E[T−t*]}。当 t* 集中于早期，指数级低于全局重跑。系：**早期可归因错误的价值最大**。

**定理 18（LEDGER 严格包含 FLUID）** T=1 且 grader 可信时，对账退化为 R69 的单步判定，逐指令一致；一般 T 下，LEDGER 在账本不可信/不可归因时退回 FLUID/R68，其它情形只在「已核验账本」上采取不更保守的局部修复，故期望风险 ≤ FLUID，安全侧单调不弱。

**定理 19（信用完整性 ⇒ 无虚假强化）** 若 CIG 成立，Type-L 的梯度权重为 0，则「侥幸能力」被固化的概率为 0（在可识别账本上），学习到的能力关于已核验账本单调。反之若去掉 CIG，存在一个以概率 q>0 侥幸成功、且被无限强化的构造，其虚假能力随训练步数单调上升。

**定理 20（干预安全与无突变）** 步骤级干预 κ 经 C-RAS-WM 认证（定义 317/325）后物理风险 ≤ ε_int；回滚只回到安全可达集内的前缀，重问/重看不改变安全包络；失败/超时/投毒时 λ 单调不降地退回 R69/R68；R68 的换装不变式与 R69 的交互安全（定理 17）保持 ⇒ 控制连续、无突变。

## 6. 本轮最大风险

**一句话**：LEDGER-RAS 的全部安全性押在「过程评分器因果忠实、且契约谓词可独立核验」这一前提上——**若评分器可被策略『表演』（process reward hacking）、或被训练数据/投毒/分布漂移吸收，系统会自信地给一个侥幸成功盖上『已学会』的章，或把一个正确步骤误判为罪魁而回滚掉正确前缀**；打分错、归因错，比不打分更危险，因为它把 R69 的「诚实的不知道」升级成「有账本背书的错误」。

**次级风险与缓解**：
1. **契约谓词本身有偏/不可核验** → 多谓词冗余 + 人类研究（E315）+ 谓词置信并入 CT；
2. **反事实回放的 sim-to-real 落差** → 回放只做证据之一、不单独定案（定义 315-d）+ 在线 A/B 校准；
3. **回滚本身不安全或不可逆** → 定义 325 可达安全集 + C-RAS-WM 认证 + 定理 20；
4. **评分器被投毒/共谋** → 分布式账本多评审（定义 324）+ ℰ_LEDGER 对抗训练 + 引理 21 吸收检测；
5. **Type-N 过度保守拖累效率** → 仅按 U_ale 收紧 + 优先重试，不进入学习；
6. **审计预算被长程放大** → T-VoI 只在高价值处审计 + 异步归因 + 预算硬约束。

```python
# IP-264 VLA-G：指令→带契约的子句
def decompose_instruction(ell):
    return [(cl, predicate(cl), tol(cl)) for cl in parser(ell)]

# IP-265/266 SCD + PCA：逐步记分并对账
def ledger_rollout(policy, scd, obs, ell):
    clauses, V_prev, ledger = decompose_instruction(ell), 0.0, []
    for t in range(horizon):
        a = policy.act(obs[t], ell)
        m = match_contract(clauses, t, obs[t])      # 契约谓词，独立核验
        V = scd.value(obs[t], ell)                    # 过程侧 V_t
        ledger.append(dict(t=t, a=a, V=V, delta=V-V_prev, m=m,
                           u=scd.uncertainty(obs[t])))
        V_prev = V
    R = task_success(obs[-1], ell)                    # 结果侧
    return ledger, R, R - ledger[-1]['V']

# IP-266/267 PCA + CIL：残差→分型→归因
def reconcile(ledger, R, rho, stats):
    if abs(stats.bias) > TAU_BIAS:            return ('TYPE_GRADER', None)
    if R >= 1 and ledger[-1]['V'] >= TAU_OK:  return ('TYPE_E', None)
    if R >= 1 and ledger[-1]['V'] <  TAU_OK:  return ('TYPE_L', None)   # 侥幸
    if R <  1 and ledger[-1]['V'] >= TAU_OK:  return ('TYPE_N', None)   # 倒霉
    t_star = argmax(ledger, key=lambda s: abs(s['delta']))
    if not counterfactual_raise(ledger, t_star):        return ('TYPE_Q', None)
    if contract_mismatch(ledger[t_star]):               return ('TYPE_B_SEM', t_star)
    return ('TYPE_B_EXEC', t_star)

# IP-268 CRD：按类型决定局部修复 / 全局保守
def credit_risk(kind, t_star, U_ale, U_epi):
    if kind == 'TYPE_E':       return dict(repair=None,    lam=lam_floor(U_ale))
    if kind == 'TYPE_N':       return dict(repair='retry', lam=lam_floor(U_ale))
    if kind == 'TYPE_B_EXEC':  return dict(repair='rollback', from_step=t_star-1,
                                           lam=lam_floor(U_ale))
    if kind == 'TYPE_B_SEM':   return dict(repair='re-ask', i=clause_of(t_star),
                                           lam=lam_floor(U_ale))
    return dict(repair='global', lam=lam_floor(U_ale + U_epi))

def credit_integrity_gate(ledger, kind):
    if kind == 'TYPE_L':
        quarantine(ledger); alarm('SPURIOUS_SUCCESS'); return False
    if kind in ('TYPE_Q', 'TYPE_GRADER'): return False
    return True

```

## 4. 推导

**引理 19（单次侥幸不可作为证据）** 鞅校准下 `E[ρ]=E[R−V_T]=0`，故单次 R=1 无法区分 Type-E 与 Type-L；区分须依赖 `(V_T, m_t)` 联合与总体偏置 b。系：任何「成功即正样本」的学习器都在吸收运气，CIG 必要。

**引理 20（局部归因的修复增益）** 失败可归因到 t* 且 φ>0、ψ>0 时，回滚修复期望执行代价 ≤ (T−t*)/T 倍全局重启，成功率恢复不低于全局保守；归因不集中则全局保守不劣。系：越可分、越靠前的错误，局部修复越值钱（与 R69 引理 16 同构）。

**引理 21（评分器吸收的判别性）** `A=1[s_φ高]·(1−m_t)·(1−ψ_t)`；执行层退化而评分器近视时 A→1，而 R69 FMA 可能因动作仍在密度高脊上不报警。`(m_t↓, ψ_t→0, s_φ↑)` 是 LEDGER 特有的吸收模式。

**引理 22（复合误差与局部化收益）** `F_T=1−(1−p)^T`；平均后缀长 `E[T−t*]` 时局部修复下有效失败增长为 `F_{E[T−t*]}`；t* 集中于早期则指数级优于全局重跑。

**定理 18（LEDGER 严格包含 FLUID）** T=1 且 grader 可信 ⇒ 逐指令退化为 R69；一般 T 下，账本不可信/不可归因时退回 FLUID/R68，其余仅在已核验账本上做不更保守的局部修复 ⇒ 期望风险 ≤ FLUID，安全侧单调不弱。

**定理 19（信用完整性 ⇒ 无虚假强化）** CIG 成立时 Type-L 梯度权重为 0，「侥幸能力」固化概率为 0（在可识别账本上），能力关于已核验账本单调；去掉 CIG 则存在成功概率 q>0 的侥幸计划被无限强化、虚假能力随步数单调上升的构造。

**定理 20（干预安全与无突变）** κ 过 C-RAS-WM 认证后物理风险 ≤ ε_int；回滚限安全可达集，重问/重看不改安全包络；失败/超时/投毒时 λ 单调不降退回 R69/R68；继承 R68 换装不变式与 R69 定理 17 ⇒ 控制连续、无突变。

## 7. 本轮最大风险

**一句话**：LEDGER-RAS 的安全性押在「过程评分器因果忠实、契约谓词可独立核验」上——**若评分器可被策略表演（process reward hacking）、或被训练数据/投毒/分布漂移吸收，系统会自信地给侥幸成功盖上『已学会』的章，或把正确步骤误判为罪魁而回滚掉正确前缀**；打分错、归因错，比不打分更危险，因为它把 R69 的「诚实的不知道」升级成「有账本背书的错误」。

**次级风险与缓解**：契约谓词有偏/不可核验（多谓词冗余 + E315 + 谓词置信并入 CT）；反事实回放 sim-to-real 落差（只作证据之一 + 在线校准）；回滚不安全/不可逆（可达安全集 + C-RAS-WM + 定理 20）；评分器投毒/共谋（分布式账本 + ℰ_credit 对抗训练 + 引理 21 吸收检测）；Type-N 过度保守（仅按 U_ale + 优先重试、不学习）；审计预算被长程放大（T-VoI 高价值处审计 + 异步归因 + 预算硬约束）。
