# 第 45 轮（承接第 44 轮 v21；本轮灵感：并发推理 × MuJoCo） · Conc-Cert × Sim-Cert：把「推理」升为可线性化的证书事务，把「MuJoCo」升为带残差管的可证仿真器（四层架构 v10-sched + 证书账本/仿真证据横层）

> 承接第 44 轮 v21（Pose-Cert × Data-Cert）。v21 把姿态升为根信任、把采集升为审计闭环，但它与 v19–v21 整个证书栈仍共享两个未言明假设：**(H4) 证书的签发、读取、刷新、组合是「单线程、原子、同一快照」的**——一次决策内姿态证书、查表、监控、租约刷新看到同一个一致世界状态；**(H5) MuJoCo 是证书的物理真值 oracle**——在仿真里成立的安全谓词与覆盖，可以迁移到真实或其他仿真，且结果由确定性物理决定。二者都不成立。H4 不成立在：L2 分支池、VLM 并行采样、并行 rollout、边缘多线程 INT8 会让证书被并发读写，产生 TOCTOU（检查时有效、执行时已过期）、非原子租约刷新、乱序/重复合并、快照撕裂——每张证书单独 sound，组合后仍可不 sound。H5 不成立在：MuJoCo 用软约束/正则化互补解接触，允许穿透、摩擦锥近似、受 timestep、solver 迭代、warm-start、约束排序与浮点归约影响；「在 MuJoCo 里证过」只是「在某个模型 + 某个数值调度下证过」。两个灵感词精确命中同一根问题：**证书的正确性是相对于执行调度的**——推理调度决定它读到什么，数值求解调度决定仿真给出什么。于是本轮把「调度相对 soundness」提升为一等公民：并发推理 → **可线性化、快照一致、ACI 汇合的证书事务账本**；MuJoCo → **接触残差可界、指纹可复现、仿真证据与真机锚点双账**的仿真证书。二者耦合出新问题：**并行仿真既是证书的评测器又是证书的生成器，若评测调度与部署调度不同、且仿真残差未被计入，证书会在「幸运调度 + 幸运求解器设置」下通过，在部署调度下静默失效（Heisen-cert）**。

## 0. 直觉与动机

**灵感 1（并发推理 → 证书不是变量，而是事务）**
直觉：并发系统里最贵的 bug 不是算错，而是「读到了不该读的旧值」。证书栈最危险的形态是：守卫用 epoch=7 的姿态证书算出一个安全 margin，然后在真正下发动作前，租约已被刷新到 epoch=8 且半径变大，或者另一线程把查表项改了——检查与执行之间世界变了（TOCTOU）。因此把证书存储当数据库：签发/刷新/读取/组合/失效都是带版本的事务操作，决策只读一个**不可变快照**，动作携带**快照令牌**，执行器在 act 时校验令牌 epoch 仍是当前且租约仍覆盖 act 时刻；任何不一致直接拒绝。并发的多个分支证书只能通过**满足结合/交换/幂等（ACI）的汇合算子**合并，使结果与归约顺序、线程数无关；安全类汇合取交集（对每个可能被选中的分支都安全），存在类汇合必须附带一个在该分支上可行的鲁棒策略，否则不签发。

**灵感 2（MuJoCo → 仿真器返回的是「模型内状态 + 残差」，不是真值）**
直觉：把 MuJoCo 当 oracle，就像把浮点求解器当数学证明。MuJoCo 的接触是软约束下的正则化互补问题：它允许有限穿透、用近似摩擦锥、在有限迭代后停止，接触力还不唯一；换 timestep、换 solver、改 warm-start、改约束顺序，接触结果都会变。正确的问法不是「仿真说安全吗」，而是「在模型类内、把互补残差、积分误差、参数不确定性、求解器容差全部打进一条 tube 后，物理状态是否仍在安全集内」。于是仿真证书 = **残差管 S(t) 上的 □ 提升**，而不是仿真点上的 □ 提升；同时把「仿真内覆盖」与「真机锚点覆盖」分成两本账，禁止用仿真覆盖率冒充现实证据。

**灵感 3（耦合 → 并行仿真是评测器也是生成器，必须调度不变 + 锚点独立）**
直觉：最自然的用法是并行开几百个 MuJoCo 实例搜覆盖最差层（承接 v21 的 DCL）。但这样评测集与生成集共享同一次数值求解，且并行度会改变归约顺序与求解调度；如果证书只在「这批并行跑出来的轨迹」上成立，它就沿自己的求解器伪影自我确认。解法是**三重隔离**：证书账本保证推理调度无关（快照 + ACI 汇合 + act-time 复核）；仿真证书保证数值调度无关（区间算术 + 固定归约树 + 指纹锁定，否则调度模糊测试必挂）；真机锚点保证模型无关（锚点由与采集策略无关的预注册集产生，禁止被并行搜索反向优化）。三者任一失败 → fail-closed。

**耦合升级**：CCL（证书事务账本）把并发推理变成可线性化、可重放、可审计的证书事务；SCE（仿真证书引擎）把 MuJoCo 变成带接触残差管、带指纹、带锚点双账的可证仿真器；SVA（调度审计器）用调度模糊、线性化模型检查、仿真伪影检测做红队。四层架构由 v9 升级为 v10-sched：新增贯穿全栈的 **证书账本横层（epoch/snapshot/join）** 与 **仿真证据横层（fingerprint/residual/anchor）**，其余层级只做接口升级，不推倒。

## 1. 形式化定义（增量：定义 56–61）

**定义 56（证书事务、快照一致性与 check–act 融合）**
证书存储是一个并发对象，状态包含姿态证书、查表项、租约、护照与审计结果，带单调 **epoch**。操作集 O={issue, refresh, read, compose, invalidate}。一次决策 D 绑定一个**不可变快照** S_e（epoch=e）：D 只能读取 S_e，所有被使用的证书必须满足 cert.epoch ≤ e 且属于 S_e 的同一次序列化。**线性化**：存在把每个操作映射到其调用/响应之间某点的全序，使每次 read 返回该点前最后一次写的结果。**check–act 融合**：守卫输出 `token=(e, cert_ids, lease_expiry, act_deadline)`；执行器在 act 时刻校验 (i) 当前 epoch 仍是 e 或该 token 已通过版本化验证协议前移（见下），(ii) 所有租约在 act 时刻 t_act 仍满足 r(t_act) ≤ r_max，(iii) 令牌未被失效。**命题（无陈旧使用）**：若 D 使用快照一致证书、每张证书在其线性化点有效且租约覆盖到 t_act、且执行只消费令牌绑定的快照（act 前不重读可变状态），则不存在「检查有效、执行失效」的陈旧证书被使用。**版本前移协议**：若 epoch 在 check 与 act 之间前进，只允许在「新 epoch 中参与该动作的每个证书仍是同一物理量且半径不增、租约到期时间不早于旧值」时原子迁移令牌，否则拒绝。

**定义 57（并发分支证书的汇合代数）**
设并发推理产生分支池 b_1..b_k，分支 b_i 的证书集为 C_i（含安全集/半径/租约/护照）。**安全汇合** ⊓：C = ⊓_i C_i，逐点取安全集交集、margin 取下确界（因执行器可能选中任一分支，必须对全部潜在选择安全）。**存在汇合** ⊔：C = ⊔_i C_i 仅在附带选择器 σ 与在 σ 所选分支上可行的鲁棒策略 π 时才签发；否则只报告「存在但不可执行」。**公理**：⊓ 满足结合、交换、幂等（ACI）⟹ 归约与顺序、线程数无关；若引入实时优先级/时间戳，则定义有序汇合 ⊑，并证明 ⊑ 的结果细于（⊆）⊓。**单调性**：加入分支只会缩小安全集（⊓ 单调不增），故任意时刻提前停止都安全（anytime safety）。**失败语义**：任一分支为未观测层/失效/护照缺失 → 该分支被剔除；若剔除后为空或存在汇合缺鲁棒策略 → fail-closed。**命题（组合 soundness）**：若每个 C_i 对其分支 sound，且执行器只选择被 ⊓ 或已证 σ 覆盖的分支，则组合决策 sound。

**定义 58（MuJoCo 接触残差与仿真 tube）**
把接触动力学写成互补系统：gap φ_i(q)≥0、法向力 λ_i≥0、φ_i λ_i=0，摩擦满足锥约束。MuJoCo 在容差下解其正则化/软约束版本，实际给出 φ_i ≥ −ε_pen、λ_i ≥ 0、φ_i λ_i ≤ ε_comp、摩擦锥残差 ≤ ε_fric、迭代停止残差 ≤ ε_sol。定义四类界：
- **接触残差** r_comp = g_comp(ε_pen, ε_comp, ε_fric, ε_sol, cond(J), warm_start)；
- **积分误差** r_int ≈ C·(e^{L_f T}−1)/L_f·h^p（f 为 L_f-Lipschitz、p 阶积分、零阶保持控制）；
- **参数不确定性** r_param（质量/惯量/摩擦/执行器/延迟的区间）；
- **数值调度差** r_sched（线程数/归约顺序/约束排序引起的差异，可由区间算术消除者取 0）。
**仿真 tube** S(t) = B(q_sim(t), r_comp + r_int + r_param + r_sched)。**命题（模型内 sound）**：若真实系统属于该模型类、上述残差界成立，则 q_true(t) ∈ S(t)。**注意**：S(t) 只保证「模型类内」，不保证「现实」；sim-to-real 需要锚点（定义 60），二者不可混为一谈。

**定义 59（调度不变证书范式）**
证书转录 T = (engine, version, integrator, timestep, solver, iterations, cone_model, warm_start, seed, thread_count, constraint_order, reduction_tree)。**调度不变**：对任意两个可接受调度 σ,σ′（推理交错 + 数值归约），判定函数 V(σ)=V(σ′)。**充分条件**：所有数值用外舍入区间算术、所有归约按稳定键排序且算子 ACI、无墙钟依赖分支、随机性由记录种子驱动 ⟹ V 调度不变。**命题**：满足充分条件时，并行评测结果可直接用于部署证书；否则必须经 SVA 调度模糊（定义 61）且出现分歧即 fail-closed。**推论**：把「并行度」写进指纹，禁止用不同并行度的评测结果互相比较。

**定义 60（仿真相对覆盖、指纹与真机锚点双账）**
覆盖声明必须是二元组 (Ĉov_sim, Ĉov_anchor) 并附模型差界。数据护照（定义 47）扩展为 π_i = (…, sim_fingerprint, residual_report, anchor_overlap)。**双账命题**：仅当 (i) 仿真指纹完整；(ii) 接触残差管未越界；(iii) 独立真机锚点上的覆盖下界 ≥1−α−ε_anchor——才允许把仿真覆盖作为部署证据。**求解器伪影利用**：存在策略使 Ĉov_sim 上升而 anchor 覆盖下降（如利用允许穿透/软接触），定义为 sim-artifact exploit；SVA 必须主动搜索并检出。**独立性**：锚点集由预注册分层抽样产生，采集策略不可读、不可反向优化（承接定义 49）。

**定义 61（调度相对 soundness 与 fail-closed 融合）**
证书 c 是 **σ-sound**，若在调度 σ 下其导出谓词成立。部署调度 σ_dep 已知且证书 σ_dep-sound，或证书调度不变，或 act-time 在 σ_dep 下复核通过——三者之一才可使用。**组合定理**：若每个子证书在其对应调度上 sound、组合算子 ACI 且组合过程不引入新调度假设、check–act 令牌在同一快照内完成，则整体在部署调度上 sound。**fail-closed 触发器**：未知/变化调度、epoch 失配且无法安全前移、汇合非 ACI 或出现分歧判定、仿真残差超界、指纹缺失、锚点覆盖不足、调度模糊检出不一致——任一触发即膨胀到保守先验或安全停机，并按定义 46 级联失效。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-63 CONC-CERT-LEDGER（并发证书事务账本 CCL）
1. **版本化证书存储**：单调 epoch、写时复制/RCU 快照、CAS 原子刷新（姿态租约、查表、护照、审计结果同账）。
2. **check–act 融合令牌**：守卫返回绑定 epoch 的令牌；执行器 atomically 复核 epoch/租约/失效位；支持「安全前移」协议，否则拒绝。
3. **ACI 分支汇合**：安全取交、存在需鲁棒策略；稳定键排序 + 确定性归约树；有序汇合作为优先级扩展。
4. **可重放账本**：append-only 哈希链记录证书转录，支持按调度指纹重放与审计（无丢失、无重复、线性化可检查）。

### 2.2 IP-64 SIM-CERT-ENGINE（仿真证书引擎 SCE）
1. **MuJoCo 指纹与配置锁**：引擎版本/积分器/timestep/solver/迭代/摩擦锥/种子/线程数/约束排序全部锁定并哈希。
2. **接触残差仪表与 tube**：从求解器输出测穿透、互补松弛、摩擦锥残差、迭代残差，结合灵敏度界出 r_comp；叠加 r_int/r_param/r_sched 得 S(t)。
3. **仿真相对证书**：安全谓词只在 S(t) 上做 □ 提升；把「模型差」与「执行差」分账；未锚定的覆盖不得升级为现实证据。
4. **求解器伪影红队**：构造利用软接触/穿透/摩擦近似的策略，验证能否在 anchor 上露馅；输出 exploit 语料回灌 ICV。

### 2.3 IP-65 SCHEDULE-AUDITOR（调度与仿真证据审计器 SVA）
1. **调度模糊测试**：随机线程数、抢占点、时钟抖动、warm-start、约束排序、归约树，检查判定是否调度不变。
2. **线性化/TOCTOU 模型检查**：对证书账本历史做线性化检查，注入「check 与 act 之间刷新/失效」场景。
3. **汇合代数合规检查**：验证分支汇合 ACI、有序汇合细化、anytime 单调性、失败语义。
4. **仿真伪影与锚点对账**：检测 sim 覆盖上升而 anchor 不升、残差越界、指纹漂移、跨并行度比较。

## 3. 四层架构 v10-sched

```
根信任层:
  PSE(姿态证书, epoch, 区间半径) → CCL 快照/账本（证书事务）
    → 未观测层/退化/epoch 失配 → fail-closed（级联失效）
L1: 几何/物体/人 → 谓词在 SCE 的仿真 tube S(t) 上 □ 提升
    └─ 每个结论引用 (pose_epoch, sim_fingerprint)
L2: CTC + VLM + IP-35 仲裁 → 并发分支池 b_1..b_k
    → CCL ⊓/⊔ 汇合（ACI + 有序细化 + 存在需鲁棒策略）
    → 检索键含 epoch / ω / 护照 / 指纹
L3: IP-51 CAR(快照+令牌; margin = min(查表, 租约, persona) − L_φ·rad(P_t) − L·rad(S(t)))
    → IP-49 □ → IP-47 组合 → IP-39 规划 → IP-45 总线 → IP-53 区间监控
L4: IP-61 DCL(覆盖驱动采集) ← IP-62 CCA + IP-65 SVA(调度模糊/伪影/锚点)
    → SCE(残差管/指纹) → 重校准 → 双账覆盖 → RCA 重颁 → 证书热更新
运行期: 快照 → 分支汇合 → check-act 令牌 → act 前复核
        调度不变/act-time 复核失败或残差越界 → fail-closed
```

def read_snapshot(store):
    e = store.epoch.load(acquire=True)
    snap = store.snapshots[e]            # 不可变 RCU 快照
    return Snapshot(epoch=e, certs=snap.certs, leases=snap.leases,
                    tables=snap.tables, fingerprint=snap.sim_fp)

def refresh_lease_cas(store, old_ver, new_lease):
    # 单调版本 CAS：失败重读，禁止撕裂写
    while True:
        cur = store.leases[new_lease.key]
        if cur.version != old_ver:
            return Reject('version_mismatch', cur)
        if new_lease.tau < cur.tau or new_lease.radius_lo < cur.radius_lo:
            return Reject('non_monotone_refresh')   # 刷新不得偷偷放宽
        if store.compare_and_swap(cur, new_lease.with_version(old_ver + 1)):
            return Accept(new_lease.version)

def issue_token(snap, certs_used, t_check, act_deadline):
    for c in certs_used:
        assert c.epoch <= snap.epoch
        assert c in snap.certs and c.valid_at(t_check)
    lease_exp = min(c.lease.expiry for c in certs_used)
    return Token(epoch=snap.epoch, cert_ids=[c.id for c in certs_used],
                 lease_exp=lease_exp, act_deadline=act_deadline)

def validate_token(store, token, t_act):
    if t_act > token.act_deadline or t_act > token.lease_exp:
        return Reject('stale_or_expired')
    cur = store.epoch.load(acquire=True)
    if cur == token.epoch:
        return Accept()
    # 版本前移：仅当新 epoch 中同物理量证书半径不增、到期不早于旧值
    for cid in token.cert_ids:
        old, new = token.snapshot.certs[cid], store.snapshots[cur].certs.get(cid)
        if new is None or not new.same_physical_quantity(old) \
           or new.radius_lo > old.radius_lo or new.expiry < old.expiry:
            return Reject('unsafe_epoch_advance')
    return Accept()

def join_safe(cert_sets):
    # 稳定键排序 + 结合交换幂等算子；顺序/线程数无关
    keyed = sorted(cert_sets, key=lambda C: stable_key(C))
    acc = Universe()
    for C in keyed:
        if C.unseen_stratum or C.invalid or C.passport_missing:
            continue                                   # 剔除不可用分支
        acc = acc.intersect(C.safe_set).min_margin(C.margin)
    return acc if not acc.empty else FailClosed('no_safe_branch')

def join_exists(branches, selector):
    feasible = [b for b in branches if b.exists_cert and b.robust_policy is not None]
    chosen = selector.choose(feasible)
    if chosen is None:
        return Unresolved('exists_but_no_robust_policy')
    return ExistsCert(union=fold(union, feasible), selector=chosen,
                      policy=chosen.robust_policy)

| epoch 前移失败导致频繁拒动 | 中-高 | 安全前移协议；分级降级；监控误拒率并调 act_deadline |
| 区间算术过保守 → 可用性下降 | 中-高 | 分账最小化；仅安全谓词用 □；E107 可用性门槛 |
| 线性化检查最坏指数 | 中 | 受限操作集 + 启发式枚举 + 失败即 fail-closed |

## 6. 本轮最大风险

**一句话**：本轮把 soundness 从「相对姿态」进一步下沉为「相对调度 + 相对仿真器数值残差」——若把 MuJoCo 的软接触/摩擦松弛误当物理真值，又允许并发推理在非快照一致的状态上组合证书，证书就会在某个幸运调度与幸运求解器设置下通过、在部署时静默失效（Heisen-cert）；因此 E103（线性化/TOCTOU）、E105（调度模糊）、E106/E107（接触残差管）、E109（仿真伪影/锚点）必须设为红线，默认回退到「单调度、单快照、纯查表/安全停机」这条永不失 sound 的底线。
