# 第 2 轮迭代 · 支线 B（灵感循环 v2b：「边缘计算」×「机器人操作系统」）—— 从「仿真神谕」推进到「边缘运行时 + ROS2/DDS 契约」

> 承接 v2（Gazebo × 实时性 × 模块化）的 UIP-01′~15。本轮不是再加一堆点子，而是用两个新词把 v2 的三条腿重新接线：
> - **边缘计算**：把选手机器视为评测链路中的“边缘推理节点”。真正要优化的是 **N 端口共享算力 × 图像载荷 × 尾延迟**，不是单次平均 FLOPs。`metadata` 是唯一能在握手时一次性优化的“观测契约”。
> - **机器人操作系统**：把提交从“一个 Python 函数”提升为“一个可被 ROS2/DDS 工具链复现、注入故障、做状态隔离的节点系统”。用 QoS / executor / lifecycle / behavior tree 的语义，给实时性与模块化补上系统层。
> 本轮最重要的新证据：Unitree 官方 `unitree_sim_isaaclab` 与真机使用**同一套 DDS 主题（domain 1）**，G1 固定底座，头部双目 1280×480 + 双腕相机，图像经 `teleimager`（ZMQ/WebRTC）发布，支持 replay / 生成数据 / `get_step_reward_value`。v2 的 Gazebo 神谕因此可以升级为 **“Gazebo 结构层 + Isaac Lab 保真层”的双层神谕**。

**两个必须写死的边界**：

1. **正式评测不是 DDS**。DDS/ROS2 只用于本地高保真风洞（replay、故障注入、端口隔离测试）；不能把本地 DDS 延迟当成官方 WebSocket 延迟。
2. **“边缘”不是机器人本体算力**。选手不能把模型塞进 G1 本体；这里的边缘指选手自己的推理服务器。我们优化的是“评测端 ↔ 边缘服务器”的契约与调度。

## 1. 上轮清单诊断（升级 / 合并 / 修剪）

- **升级为双层神谕**：UIP-11 GSO → **UIP-11′ SOS**。Gazebo 做 Tier-0（CPU、快、结构/顺序裁判）；Isaac Lab 做 Tier-1（GPU、DDS 同构、相机/接触/step reward 更接近真机）。v2 的“仿真过拟合仿真”风险，用“保真度阶梯 + 真机锚点”而不是“换一个更大的仿真”来解。
- **升级为双层数据工厂**：UIP-12 DRF → **UIP-12′**。同一套 `human_*` 撤回脚本在 Tier-0 批量生成、在 Tier-1 做形态/时机随机化确认。
- **升级为边缘运行时**：UIP-08′ LAT-ENG + UIP-15 CSG → **UIP-08″ ERF**。把“共享骨干 + 批处理 + 每端口隔离 + 可信度护栏”统一成 SLO 调度器：QoS、截止期、有界队列、每端口状态命名空间、特征缓存、早退推理。
- **升级为网络感知块长**：UIP-13 ACS → **UIP-13′ NACS**。块长不仅由“任务阶段”决定，还由服务时间、RTT、带宽和扰动检测延迟共同决定；给出可计算的稳定条件。
- **升级为行为树技能图**：UIP-14 MSGR → **UIP-14′ BTSG**。用 Sequence/Fallback/Retry/Timeout 的语义显式表达“推进 / 撤回 / 重做 / 放弃”，比扁平路由更适合 UIP-01″/09″ 的恢复逻辑。
- **合并/封存**：UIP-15 并入 ERF；UIP-04 继续封存（世界模型只在 SOS 资产缺失时补位）；UIP-10 继续封存（metadata 握手后不能切 joint/ee）；UIP-05 降为低优先级（VLA 已内建语言条件，边际收益不如边缘/OS 两条线）。
- **新增（命中两词）**：UIP-16 OCCD（观测契约协同设计）、UIP-17 AEI（单骨干多早退口）、UIP-18 DIL（DDS-in-the-loop 风洞）。

## 2. 直觉解释

### 2.1 边缘计算：瓶颈是“载荷 × 频率 × 端口”，不是“模型 FLOPs”

一次 `get_action` 要传 4 张图；如果 `obs_delta_indices` 叠 T 帧，就是 4T 张 JPEG。N 个端口共享一个后端时，边缘节点的压力近似正比于
`图像字节数 × 请求频率 × 端口数`。

而请求频率不是控制频率，而是 `f_c / k`：块长 k 越长，请求越少、带宽越低，但对人为撤回的反应越慢。**k 同时是实时性旋钮和带宽旋钮**。这就是本轮把“边缘”与“实时”接在一起的地方。

### 2.2 机器人操作系统：可复现、可隔离、可注入故障

ROS2/DDS 给我们的不是“更快的模型”，而是三件工程能力：

1. **契约**：topic + message + QoS，明确“谁是传感器、谁是命令、丢了怎么办”；
2. **隔离**：N 个端口对应 N 个 episode，状态、缓存、行为树黑板必须按端口命名空间隔离；
3. **可观测**：时间戳、延迟、队列深度、丢帧、动作统计都能被记录和回放。

没有这三件事，N 端口并发下的“尾延迟”和“reset 污染”只能靠猜。

### 2.3 合起来：契约感知的边缘运行时

`metadata` 是“观测契约”，ROS2 QoS 是“传输契约”，UIP-13′ 是“时间契约”，UIP-01″/09″ 是“任务契约”。四者对齐后，才能在 N 端口、图像载荷、人为撤回同时存在时，把成功率和步骤分守住。

## 3. 严谨定义

### 3.1 观测契约与载荷

定义观测契约
\[
C=(K,R,\Delta),\quad K\subseteq\mathcal{K},\; R=\{R_k\},\; \Delta=\{\Delta_k\},
\]
其中 \(K\) 是声明的 key 集合，\(R_k=[H_k,W_k]\) 是 resize，\(\Delta_k\) 是帧偏移列表。单次请求的载荷
\[
B(C)=\sum_{k\in K}|\Delta_k|\cdot J_k(R_k),
\]
\(J_k(R_k)\) 是 key \(k\) 在分辨率 \(R_k\) 下的 JPEG 字节数。若控制频率为 \(f_c\)、块长为 \(k\)，则每端口平均带宽
\[
\dot B(C,k)=B(C)\cdot\frac{f_c}{k}.
\]
**推论**：增大 k 同时降低请求频率和带宽，但线性增加“两次观测之间的盲区时间” \(k/f_c\)；人为撤回恰好发生在这个盲区里。因此 k 的下界由服务时间决定，上界由扰动检测延迟决定。

### 3.2 边缘 SLO

定义一步的 SLO 元组
\[
\mathcal{S}=(D,\epsilon,\sigma_{\max},\mathcal{A}),
\]
要求
\[
\Pr(L_t\le D)\ge 1-\epsilon,\qquad \mathrm{std}(L)\le\sigma_{\max},\qquad \mathrm{stats}(A)\in\mathcal{A},
\]
其中 \(L_t\) 是第 t 次 `get_action` 的端到端延迟，\(\mathcal{A}\) 是“动作统计不异常”的允许集（对应 README §6 的可信度）。**优化目标不是均值，而是尾概率。**

### 3.3 稳定条件（块长的硬下界）

设一次推理服务时间为 \(S\)，网络往返为 \(R\)，控制频率为 \(f_c\)。评测端执行完一个 k 步块后才会再次调用；若
\[
S+R > \frac{k}{f_c},
\]
则块已执行完而下一块还没到，评测端出现**空转/等待**，延迟和抖动被放大。因此必须
\[
k \ge f_c\,(S+R).
\]
这是 UIP-13′ 的硬约束。接触密集步想用小 k，就必须同时用 UIP-17 早退或 UIP-16 降载荷把 S 压下来；否则小 k 反而制造 stall。

### 3.4 帧缓存命中率

若叠帧偏移是长度 T 的滑动窗口，相邻两次请求共享 T−1 帧。按帧缓存视觉特征时，稳态命中率
\[
p_{\text{hit}}=\frac{T-1}{T},
\]
视觉编码计算的理论节省为 \(1-1/T\)（前提是编码器按帧编码，或可在 token 级复用）。这就是 UIP-08″ 里 FIFC 的依据；但 JPEG 解码仍需付费，所以要在 DIL 里实测净收益。

### 3.5 早退推理

单骨干在若干层 \(e=1,\dots,m\) 接早退头，成本 \(c_e\) 随 e 增加。给定置信度 \(q_e(o)\) 与阈值 \(\tau\)，选择
\[
e^*(o)=\min\{e:q_e(o)\ge\tau\}.
\]
通过离线校准 \(\tau\) 使步级错误率 \(\le\epsilon\)；接触密集阶段用更高的 \(\tau\)（更深出口），自由空间用更低 \(\tau\)。这是**一个模型多个出口**，不是多模型集成，尽量规避“单模型”合规歧义。

### 3.6 行为树技能图

行为树 \(T=(N,\text{child},\text{type})\)，节点类型 ∈ {Sequence, Fallback, Retry, Timeout, Condition, Action}。状态 ∈ {Success, Failure, Running}。恢复子树：

```
Fallback(
  Sequence(VerifyDone, Advance),
  Sequence(VerifyRegressed, Retry(Redo, max_redo)),
  Sequence(VerifyFail, Retry(RetrySkill, max_retry)),
  Continue
)
```

黑板存 \(g\)（当前计分步）、`redo`、`conf`、`deadline`。这比 v2 的扁平技能路由多出**失败/撤回的显式语义**。

### 3.7 双层神谕的保真度阶梯

定义保真度偏序
\[
F_0(\text{Gazebo}) \prec F_1(\text{Isaac Lab/DDS}) \prec F_2(\text{真机}).
\]
Tier-0 负责“广撒网”的结构/顺序筛选；Tier-1 负责“高保真确认”；真机负责“校准锚点”。任何结论必须标注是在哪一层得到的，不能把 \(F_0\) 的结论写成 \(F_2\)。

## 4. 瓶颈假设（更新）

- **H1（最高杠杆）**：N 端口下真正的约束是**尾延迟 + 带宽 + 状态隔离**，而不是平均吞吐。`P99` 和 stall 率会同时伤成功率和可信度。
- **H2**：`metadata` 是全局一次性的观测契约，无法按任务切换；为 32 任务声明“全能观测”会支付固定带宽税。**鲁棒契约优化**能在不降成功率的前提下显著降载荷。
- **H3**：块长 k 是“反应性—带宽—稳定性”的三向旋钮；存在由 \(k\ge f_c(S+R)\) 给出的硬下界和由人为撤回检测延迟给出的软上界。
- **H4**：DDS/ROS2 对“时序、主题、相机、状态隔离”的保真度高，对“官方 WebSocket 延迟”的保真度低；DIL 只能用于结构/故障/隔离，不可用于榜单预测。
- **H5**：恢复策略的收益上限由验证器决定；一次误判 `regressed` 在尾延迟约束下可能比漏判更伤，必须用滞回 + 置信度 + 重做预算。

## 5. 候选与合并 → v3

围绕两词发散 8 个草案，合并后得到：

- **保留/升级**：UIP-01″、02″、08″、09″、11′、12′、13′、14′；
- **新增**：16 OCCD、17 AEI、18 DIL；
- **降级/封存**：UIP-05 低优先级；UIP-15 并入 08″；UIP-04、10 继续封存。

旗舰仍是 **UIP-01″（RHPV-D + BT 恢复）**，次旗舰是 **UIP-09″（DCR-R）**；本轮新增的“边缘”腿由 **08″/16/17** 支撑，“OS”腿由 **18/13′/14′** 支撑。

## 6. 本轮最大风险

**一句话**：把本地 DDS/Isaac Lab 的时序与保真度当成官方 WebSocket 评测的代理，会优化错延迟预算并过拟合仿真；必须把正式 WebSocket/msgpack 边缘风洞作为延迟的唯一真源，把真机作为保真度的锚点。

## 1. 旗舰与次旗舰：UIP-01″ RHPV-D × UIP-09″ DCR-R

### 1.1 机制

- 动作块 `A=(a_1..a_{T_a})` 不整段盲执行。每 `k` 步（或每个块边界）用验证器 `V(o_t,l,g)` 判断当前计分步 `g` 的状态 ∈ {`done`,`ongoing`,`fail`,`regressed`}。
- `regressed` 由两条证据触发：① 时序差分（`g` 从 done 回退到 undone）；② 视觉/几何判据（如拉链从闭合回到打开、叠好的毛巾被翻开）。
- **v3 新增**：
  1. **滞回**：连续两次 `regressed` 或单次置信度 > 0.8 才重做，降低误判振荡；
  2. **deadline-aware redo**：若重做会使 `S_redo+R > k/f_c` 超出当前块预算，则不在本块内重做，而是把“待重做”写入黑板，下一块优先处理；
  3. **重做预算**：每子目标最多 `max_redo` 次，超过后转 `fail` 并尝试 BTSG 的恢复子树；
  4. **BTSG 恢复语义**：推进/撤回/失败是行为树的显式分支，而不是 if-else 堆叠。
- **与 v2 差异**：v2 的 RHPV-D 只加了 `regressed` 分支；v3 把“重做”纳入边缘 SLO 与行为树，避免“检测到了但来不及重做”以及“误判导致死循环”。

### 1.2 可行性

- 高。`action_chunk_size`、`reset()`、`get_action` 均在接口内；验证器优先用**几何+语言规则**（零额外模型），或从主骨干蒸馏出内部小头。
- `regressed` 判据可以离线用 UIP-11′ 双层神谕与 UIP-12′ 数据工厂调参；在线只做轻量推理。
- 与 UIP-08″ 的端口状态隔离天然对齐：每个端口一份黑板、一份 `g/redo`。

### 1.3 资源

- 公开 32 数据集（写判据 + 弱标注）；
- 1 张推理卡（共享骨干 + 早退头）；
- 1 台 CPU 机器跑 Tier-0/DIL（可选）。

### 1.4 风险

- 误判 `regressed` 会“反复重做” → 滞回 + 置信度门限 + 最大重做次数 + 延迟预算；
- 人为撤回的时机在仿真与真机之间可能差异大 → UIP-12′ 做时机/速度/轨迹随机化，真机锚点校准。

## 3. UIP-11′ 双层神谕 SOS 与 UIP-12′ 双层数据工厂

### 3.1 为什么升级

v2 只有 Gazebo。Gazebo 的优点是 CPU、快、可并行、低层关节控制忠实；缺点是视觉/接触保真度有限。官方 `unitree_sim_isaaclab` 补上了另一头：**与真机相同的 DDS 主题（domain 1）**、G1 固定底座、头部双目 + 双腕相机、`teleimager` 图像服务、replay/generate、`get_step_reward_value`。因此本轮不再二选一，而是做**保真度阶梯**：

| 层级 | 引擎 | 主要用途 | 成本 | 结论强度 |
|---|---|---|---|---|
| Tier-0 | Gazebo / `unitree_ros` | 32 任务广撒网；结构/顺序/计分步几何谓词；CPU 多实例 | 低 | 结构代理 |
| Tier-1 | Isaac Lab / `unitree_sim_isaaclab` | 5–8 个高价值任务的视觉/接触/时序确认；DDS 同构；数据生成 | 中高（GPU） | 保真代理 |
| Tier-2 | 真机预约 | 校准锚点；最终结论 | 高 | 真结论 |

任何论文/汇报必须标注层级：`Tier-0` 不能写成真机，`Tier-1` 也不能写成真机。

### 3.2 Tier-0：Gazebo 结构神谕

- 场景：G1 29-DoF 固定底座 + Dex1 + 桌面资产 + 与真机同名义的相机位。
- 判分：用几何谓词判每个计分步（见 §6 示例），得到 episode 级 step-score 代理。
- 优势：CPU headless 可并行几十个实例；适合 OCCD 的大规模契约搜索和 NACS 的参数扫描。
- 局限：视觉/接触 sim-to-real gap；只当“结构/顺序”裁判。

### 3.3 Tier-1：Isaac Lab/DDS 保真神谕

- 场景：G1 29-DoF fixed base；头部双目 1280×480 side-by-side + 左右腕；`teleimager` ZMQ/WebRTC；`render_fps` 默认 30、`step_hz` 可配。
- 接口：与真机相同的 DDS 主题（`rt/lowcmd` / `rt/lowstate` / Dex1 等），domain 1。
- 数据：支持 replay 与 `--generate_data`，可在回放时改光照/相机参数重采集；`get_step_reward_value` 可读离散 step reward。
- **限制**：官方任务场景目前是少量 pick/place/stack/drawer/wholebody 变体，不是 32 任务全覆盖。因此 Tier-1 只用于**代表性子集**（建议 T19 拉链、T26 插网线、T27 叠碗、T16 叠毛巾、T23 球拍、T12 开锁），其余仍靠 Tier-0。不要假设“Isaac Lab 一键覆盖 32 任务”。

### 3.4 UIP-12′：扰动-恢复数据工厂

- 在 Tier-0 用脚本化机械手复现 `human_*` 撤回（拧回、翻开、拉开、拿走、挪底座、放回起点）；
- 在 Tier-1 对同一扰动做**时机/速度/轨迹/视角随机化**，生成 `(干扰前 → 撤回 → 恢复)` 三元组；
- 训练两个东西：① 策略的 `regressed` 识别与恢复；② 验证器的撤回判据；
- 评测：在人扰轴上单独报告 step-score，不与无干扰数据混在一起。

**风险**：仿真干扰 ≠ 真机人为干扰；用随机化覆盖形态，用真机锚点校准时机。Tier-1 的资产不足时，不要硬造 32 个场景；优先做“撤回型干扰最明确”的 11 个任务。

## 4. UIP-08″ 边缘运行时 ERF + UIP-16 OCCD + UIP-17 AEI

### 4.1 ERF 架构

```
[评测端 N 端口] --WebSocket/msgpack(JPEG q95)--> [每端口 Edge Gateway]
        -> [Admission Control / Deadline Scheduler]
        -> [Per-port State Namespace: reset, BT blackboard, cache]
        -> [Frame Cache + Feature Cache]
        -> [Shared Backbone + Early-Exit Heads]
        -> [Action Chunk Postprocess + Credibility Guard]
```

- **共享后端**：一个骨干服务 N 个端口；批处理请求，但**每端口状态隔离**（`reset`、历史、缓存、黑板都以 port_id 为命名空间）。
- **有界队列**：每端口只保留最新请求/最新观测，避免旧请求堆积放大尾延迟；对应 ROS2 sensor QoS 的“latest value”语义。
- **SLO 控制器**：以 `(D, ε, σ_max, A)` 为约束，动态决定批大小、早退口、是否降分辨率/减叠帧、是否投机预计算。
- **可信度护栏**：动作形态平滑、异常值裁剪、最大重试/重做次数、延迟超预算时降级而不返回畸形动作（原 UIP-15 合并于此）。
- **契约映射**：正式传输是 WebSocket，不是 DDS；但内部用 QoS 语义管理“哪些帧可丢、哪些命令必须可靠、队列深度多少”。这是“用 OS 思想做边缘”，不是“把 DDS 塞进评测链路”。

### 4.2 UIP-16 OCCD：观测契约协同设计

**问题**：`metadata` 在握手时一次性确定，之后不能按任务切换。为 32 任务声明“全能观测”（4 图 × 长叠帧）会支付固定带宽税；声明太少又会丢信息。需要在**全局单一契约**下做鲁棒优化。

形式化：

\[
C^*=\arg\max_{C\in\mathcal{C}}\left[\frac{1}{32}\sum_{t=1}^{32}U_t(C)\right]-\lambda\max_t L_t(C)-\mu\max_t B_t(C),
\]
\[
\text{s.t.}\quad \Pr(L_t>D)\le\epsilon,\quad B(C)\le B_{\max},
\]

其中 \(U_t=\alpha\cdot\text{Succ}_t+\beta\cdot\text{StepScore}_t\)，\(B(C)\) 是单次请求载荷，\(L_t\) 是端到端延迟。搜索空间：

- `K`：图像 key 子集（4 图 → 2/3/4 图）、state key 子集；
- `R`：每图 `[H,W]`（如 480×640、360×480、240×320）；
- `Δ`：每 key 的帧偏移（如 `[0]`、`[-2,0]`、`[-4,-2,0]`）；
- 约束：`language` 必须 `[0]`；offset 必须 ≤0 且严格递增；resize key 必须在 `obs_delta_indices` 中。

求解：坐标下降 / 贝叶斯优化，用 Tier-0 快速评估，Top-k 用 Tier-1 确认。**不要**在 32 任务上逐个过拟合；目标是最大化最差任务的收益。

### 4.3 UIP-17 AEI：单骨干多早退口

- 在骨干若干层接早退头；每步根据置信度选择最浅可用出口。
- 成本 \(c_e\) 随出口深度增加；接触密集阶段提高阈值 \(\tau\)（更深），自由空间降低 \(\tau\)（更浅）。
- 与 OCCD 联合：deadline 紧 → 降分辨率 + 浅出口；接触密集 → 高分辨率 + 深出口。
- **合规**：这是一个模型多个出口，不是多模型集成；技能头也共享同一骨干。避免外部 VLM 验证器。

### 4.4 帧身份特征缓存 FIFC

- 叠帧滑动窗口下，相邻请求共享 T−1 帧；按 `(port_id, stack_slot)` 维护环形缓冲，缓存解码帧与视觉 token。
- 理论命中率 \((T-1)/T\)，视觉编码节省 \(1-1/T\)；JPEG 解码仍需成本，需在 DIL 实测净收益。
- **风险**：如果评测端的叠帧不是严格滑动窗口，或帧内容被替换，缓存会错位；用端口内步号 + 形状校验，必要时回退到重算。

## 5. UIP-13′ NACS 与 UIP-14′ BTSG

### 5.1 NACS：网络感知的块长

由 §3.3 的稳定条件，块长必须满足
\[
k\ge f_c(S+R).
\]
若接触密集步想用小 k，就必须先通过 AEI/FIFC/OCCD 把 \(S+R\) 压下来。反过来，k 的上界由人为撤回的检测延迟决定：若盲区 `k/f_c` 大于撤回发生的典型时间尺度，就会错过 `regressed`。

一个可执行的调度目标：
\[
k_t^*=\arg\min_{k\in[1,K]}\left[\alpha\frac{k}{f_c}+\beta\frac{B(C)f_c}{k}+\gamma\cdot\text{Risk}_t(k)\right],
\]
\[
\text{s.t.}\quad k\ge f_c(\hat S_t+\hat R_t),\quad k/f_c\le\tau_{\text{react}}.
\]

- 第一项是反应时间，第二项是带宽，第三项是错过撤回的风险；
- 接触密集/撤回型任务取较小 k，长程搬运取较大 k；
- 投机预计算：评测端执行当前块时，后台按“准静态预测”预生成下一块；观测到达后做一致性校验，一致则直接返回，不一致则重算。只在自由空间/低风险阶段启用，避免浪费算力。

### 5.2 BTSG：行为树技能图

- 节点类型：Sequence / Fallback / Retry / Timeout / Condition / Action；
- Action 节点调用技能头或动作块；Condition 节点调用验证器；
- 黑板：`g`（当前计分步）、`redo`、`retry`、`conf`、`deadline`、`phase`；
- 恢复子树：

```
Fallback(
  Sequence(VerifyDone, Advance),
  Sequence(VerifyRegressed, Retry(Redo, max_redo)),
  Sequence(VerifyFail, Retry(RetrySkill, max_retry)),
  Continue
)
```

- 与 v2 的扁平路由相比，BTSG 的收益是**可解释的失败/撤回语义**和**可组合的恢复策略**；代价是需要仔细设计 tick 时机（建议只在块边界 tick，避免每控制步都跑树）。

## 6. 关键算法（伪代码）

### 6.1 边缘运行时主循环

```python
class EdgeRuntime:
    def __init__(self, backbone, exits, bt, n_ports,
                 D_ms=200, eps=0.01, sigma_max_ms=30):
        self.ports = [PortState(i) for i in range(n_ports)]
        self.backend = SharedBackend(backbone, exits)
        self.cache = FrameFeatureCache()
        self.slo = SLOController(D_ms, eps, sigma_max_ms)

    def handle(self, port_id, obs):
        st = self.ports[port_id]              # 每端口命名空间
        C = self.slo.contract(obs)            # OCCD: keys/resize/stack
        frames = st.extract(obs, C)
        feats = self.cache.get_or_encode(frames, self.backend, port_id)
        exit_id = self.slo.pick_exit(obs, st.phase)
        chunk = self.backend.act(feats, exit_id, st)
        return self.slo.guard(chunk, st)      # 可信度/形状/延迟护栏
```

### 6.2 行为树恢复

```python
class RecoveryBT:
    def tick(self, bb):
        if self.verify_done(bb):
            bb.g += 1; bb.redo = 0; return "advance"
        if self.verify_regressed(bb):
            if bb.redo < bb.max_redo and self.deadline_ok(bb):
                bb.redo += 1
                return "redo"
            return "defer"       # 本块预算不够，下一块优先重做
        if self.verify_fail(bb):
            if bb.retry < bb.max_retry:
                bb.retry += 1
                return "retry"
        return "continue"
```

### 6.3 块长选择

```python
def pick_k(phase, S_hat, R_hat, f_c, K, deadline, react_tau):
    k_min = ceil(f_c * (S_hat + R_hat))
    k_max = min(K, floor(min(deadline, react_tau) * f_c))
    if k_min > k_max:
        return K            # 先降 S（早退/缓存/降载荷），不要硬缩 k
    if phase == "contact":
        return k_min
    if phase == "free":
        return k_max
    return (k_min + k_max) // 2
```

### 6.4 SOS 计分谓词（示例）

```python
def score_step(task, sim):
    s = 0
    if task == "T26_plug_in_ethernet":
        s += 30 if sim.gripper_holds("ethernet") else 0
        s += 30 if sim.gripper_holds("port")     else 0
        s += 40 if sim.contacts("rj45", "port") and sim.insert_depth() > D else 0
    if task == "T27_stack_bowls_three":
        s += 30 if sim.bowl_at("bowl1", "center") else 0
        s += 30 if sim.stacked_on("bowl2", "bowl1") else 0
        s += 40 if sim.stacked_on("bowl3", "bowl2") else 0
    return s        # episode 级 step-score 代理（/100）
```

### 6.5 OCCD 搜索

```python
def occd_search(tasks, oracle, budget):
    C = default_contract()
    best = evaluate(C, tasks, oracle)
    for K in candidate_key_subsets():
        for R in candidate_resizes():
            for D in candidate_stacks():
                C2 = (K, R, D)
                if payload(C2) > budget:
                    continue
                score = evaluate(C2, tasks, oracle)
                if score > best:
                    best, C = score, C2
    return C
```

## 7. UIP-18 DIL：DDS-in-the-loop 本地风洞

### 7.1 目的

把“正式 WebSocket/msgpack 传输”和“机器人侧 DDS/ROS2 时序”接在一个可重复的闭环里，用于：

- 回放真实/仿真 episode（rosbag2 或 Isaac Lab replay）；
- 注入网络故障（延迟、抖动、丢包、乱序、重复、带宽上限、时钟偏移）；
- 测试 N 端口并发、`reset` 污染、状态隔离；
- 测量 p50/p95/p99 延迟、抖动、队列深度、stall 率、动作统计、step-score。

### 7.2 架构

```
[unitree_sim_isaaclab / Gazebo / rosbag2]
        │  DDS (rt/lowstate, cameras via teleimager)
        ▼
[ROS2/DDS bridge] --convert--> [official obs format: numpy + JPEG q95]
        │                            │
        │                            ▼
        │                  [WebSocket evaluator emulator]
        │                            │  (delay/jitter/loss/reorder/bandwidth)
        │                            ▼
        │                  [Policy server: N ports, ERF]
        ▼
[step reward / geometric score] <-- [action chunks] <-- [WebSocket]
```

### 7.3 故障注入清单

- 网络：固定延迟、随机抖动、丢包、乱序、重复、带宽上限、突发；
- 观测：旧帧、重复帧、缺失帧、JPEG 质量波动、分辨率变化；
- 端口：同时 reset、单端口崩溃、慢端口拖累快端口、N 不匹配；
- 动作：形状错误、dtype 错误、NaN、块长不一致、动作统计异常。

### 7.4 指标

- 延迟：p50/p95/p99、标准差、超预算率；
- 稳定性：stall 率、队列深度、请求积压；
- 正确性：step-score、成功率、`regressed` 检出率/误报率；
- 隔离：端口间状态串扰次数、reset 后残留状态；
- 合规：动作形状/dtype/token/块长校验通过率。

### 7.5 必须写死的限制

DDS 不是官方评测传输。DIL 的延迟数字只能用于**相对比较**和**故障鲁棒性**，不能直接预测榜单；正式的延迟真源仍是 WebSocket/msgpack 的边缘风洞（可以用本地 evaluator emulator 模拟）。

## 9. 合规与风险（本轮新增重点）

- **单模型合规**：AEI 是“一个骨干多个早退口”，不是多模型；BTSG 的技能头共享同一骨干；外部 VLM 验证器仍可能被判“非单模型”，优先用几何/规则验证器或内部蒸馏小头。
- **传输边界**：正式评测是 WebSocket/msgpack，不是 DDS；不要把 DIL 的 DDS 延迟写成官方延迟。
- **metadata 全局性**：OCCD 必须输出一个全局契约，不能按任务切换；鲁棒优化优先于单任务最优。
- **仿真过拟合**：Tier-0/Tier-1 都只是代理；必须保留真机锚点（E207）。Tier-1 的任务场景并不覆盖全部 32 任务，不要假设“Isaac Lab 万能”。
- **N 端口红线**：端口数必须严格等于 N，连续 8765 起；共享后端必须并发不互堵、每端口状态隔离；`reset` 不得跨端口污染。
- **撤回误判**：`regressed` 误判比漏判更伤时，用滞回 + 置信度 + 重做预算；宁可 defer 到下一块，也不要死循环。
- **手册缺口**：5 轴中的“位置/干扰物/背景”、评测轮次/时限/控制频率仍未核实；上述 k 的数值必须等官方频率公布后重算。

## 11. 本轮最大风险 & 押注

**一句话**：把本地 DDS/Isaac Lab 的时序与保真度当成官方 WebSocket 评测的代理，会优化错延迟预算并过拟合仿真；必须把正式 WebSocket/msgpack 边缘风洞作为延迟的唯一真源，把真机作为保真度的锚点。

**→ 押注：UIP-09″（DCR-R）× UIP-12′（双层扰动-恢复数据工厂）× UIP-08″（边缘运行时）× UIP-01″（BT 恢复）**——它同时对准两个最大缺口：规则里白纸黑字、公开数据完全空白的人为撤回；以及 N 端口共享算力下最容易被忽视的尾延迟与状态隔离。两者都在选手 API/离线算力权限内，且能用双层神谕 + 真机锚点逐步去风险。
