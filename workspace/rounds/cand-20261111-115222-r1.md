# 第 55 轮（承接第 54 轮 v16 GroundEdge-GenSim+++；灵感循环第 6 轮；本轮灵感：「迭代验证」×「用户体验」）

> 第 54 轮把技能组合提升为动作-鲁棒性双证书 `J=(ρ,A_cert,γ_ce,δ_a)`，回答了“组合前能否判定、云边能否对齐”。但它默认证书一旦签发就在整个部署期内有效，也默认“任务成功”就是目标。本轮追问两件被跳过的事：**证书的时间有效期**，以及**证书对操作者的可用性**。核心矛盾：H22：证书会随分布漂移、动作磨损与用户行为耦合而衰减，一次性验证在持续监控下既无统计效力、也无撤销通道；H23：任务成功 ≠ 用户感知成功，忽略延迟、打断、可预测性、可理解性的“技术正确”会把风险转嫁给操作者，造成过度信任或信任崩塌。

## 0. 直觉与动机

**灵感 1（证书不是印章，是持续付租的租约）**
直觉：第 54 轮的 `J` 像一张一次性验收单，但机器人部署是一个持续过程。技能的动作剖面会因磨损、负载、地面材质而漂移，云边映射会因网络与算力波动而变形，用户也会“学会”系统从而改变交互分布。因此 `J` 应带一个**半衰期 `T_½`**：证据随时间指数折旧，验证不是做完一次就结束，而是按“验证预算 `B_v`”持续付租；欠租时证书自动降级为“待复核”，而不是默默继续生效。

**灵感 2（迭代验证不是多跑几次，而是 anytime-valid）**
直觉：工程上常把“每 50 次抽检一次”当作迭代验证，但只要允许在任意时刻看结果并决定停不停，固定样本量的 p 值就失效（peeking / optional stopping）。真正的迭代验证需要**任意时刻有效（anytime-valid）的证据过程**：用非负鞅/ e-process 累积证据，Ville 不等式保证在连续监控、任意停时下第一类错误仍受控。这样“边部署边验证、看到坏证据立刻停”才是统计上合法的。

**灵感 3（正向证书不能自动撤销，必须有第二条时间尺度）**
直觉：e-process 擅长证明“我还安全”，却不擅长证明“我已经不安全”——一旦长期安全把资本 `K` 推得很高，漂移发生后要先把这笔“安全储蓄”亏光才可能报警，撤销延迟随历史长度增长。本轮用 toy 仿真把这件反直觉的事量化了：在 `ρ_min=0.85`、漂移后成功率 0.72、2000 次重复下，累积 e-process 的撤销延迟中位数 **174** 步、检出率仅 **79.1%**；而 CUSUM 变点检测中位数 **56** 步、检出率 **99.75%**、预漂移误报 **0**。因此证书体系必须是**双时间尺度**：慢速 e-process 负责“签发/维持”，快速变点检测负责“撤销/降级”。这正是“迭代验证”与“一次性验证”的分水岭。

**灵感 4（用户体验是鲁棒性的可观测投影）**
直觉：任务成功率 99% 的系统仍可能让用户觉得不可用：反馈延迟 800ms、每任务打断 3 次、动作不可预测、失败后无法恢复、解释像天书。用户实际感知的是 `UPS = 任务成功 ∧ 体验约束`，而不是实验室里的 success rate。更进一步，**信任校准**是安全变量：用户过度信任（trust ≫ 实际可靠性）会在系统退化时毫无防备；信任不足则频繁接管、白白浪费自动化。UX 不能作为验收后的“包装”，必须进入证书本体。

**灵感 5（把用户当作验证预算的分配器，而不是免费标注机）**
直觉：用户反馈是最贵也最贴近真实分布的验证信号，但用户注意力有限。每次询问、每次接管都有打断成本，盲目的“多问用户”会造成验证疲劳并污染反馈。正确的做法是**体验感知的主动验证**：按单位用户成本的信息增益（VOI）分配验证动作，把预算优先投到“用户可感知且证书最不确定”的动作区域，而不是均匀撒网。

**灵感 6（体验-验证层叠加到金字塔）**
直觉：在第 54 轮的鲁棒性金字塔与动作协同层之上，再叠加 **体验-验证层 `𝕌`**：`𝕌_0` 物理/感知极限（延迟、噪声、带宽），`𝕌_1` 技能体验剖面 `U_S`，`𝕌_2` 信任校准，`𝕌_3` 迭代验证契约 `IVC`。跨层传递的证书从“动作-鲁棒性双证书”升级为“动作-鲁棒性-体验-时效四元组”，且每个证书都带自己的证据时钟。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（用户体验剖面 `U_S`）**
技能 `S` 的体验剖面 `U_S = (ℓ, ι, π, r, κ)`：
- `ℓ`：动作到反馈的 P95 延迟；
- `ι`：单任务平均打断/接管次数；
- `π = 1 - H(A_seq)/log|A|`：动作序列可预测性；
- `r = P(用户在 τ_rec 内可恢复)`：可恢复性；
- `κ`：解释可理解度（盲测理解题得分）。
体验约束为 `ℓ≤ℓ* ∧ ι≤ι* ∧ π≥π* ∧ r≥r* ∧ κ≥κ*`。**用户感知成功** `UPS(T)=1[task_success(T) ∧ 体验约束成立]`。设操作者信任 `T_t`、经验可靠性 `R_t`，则**校准误差** `CE_t=|T_t-R_t|`，**过度信任** `O_t=max(0,T_t-R_t)`。

**定义 122（验证预算与证书半衰期）**
验证预算 `B_v=(N_max, C_max^{ux}, t_max)` 分别约束验证次数、用户总打断成本与验证时长。证据权重 `w_i=e^{-(t-i)λ_d}`，有效样本 `n_eff(t)=Σ_{i≤t}w_i`，**证书半衰期** `T_½=ln2/λ_d`。**验证欠债** `D_v(t)=max(0, n_req(α,δ)-n_eff(t))`；当 `D_v>0` 时证书只能标记为“待复核”，不得继续作为部署许可。

**定义 123（anytime-valid 验证 e-process）**
证据流 `X_t∈{0,1}`（成功/失败）。检验 `H_0^{unsafe}: E[X_t]≤ρ_min`。取可预测 `λ_t∈(0,1/ρ_min)`，定义资本
```
K_t^cert = Π_{i=1}^t (1 + λ_i (X_i - ρ_min)),  K_0=1.
```
在 `H_0^{unsafe}` 下 `K_t^cert` 为非负超鞅，Ville 不等式给出 `P(∃t: K_t^cert ≥ 1/α_cert) ≤ α_cert`：只要 `K_t^cert` 越过阈值即可**任意时刻**拒绝“不安全”，无需固定样本量。对称地定义撤销过程 `K_t^rev = Π (1 + λ_i (ρ_min - X_i))`，用于拒绝 `H_0^{safe}: E[X_t]≥ρ_min`。为克服累积过程的撤销延迟，另设一侧 CUSUM 变点检测 `S_t=max(0, S_{t-1}+(ρ_min-X_t)-k)`，`S_t≥h` 触发撤销。

**定义 124（迭代验证契约 `IVC`）**
`IVC = (T_½, B_v, α_cert, α_rev, Triggers, EvidenceStack)`，其中 `Triggers = {漂移报警, 体验约束违反, 动作剖面/组合变更, 半衰期到期, 信任校准越界}`。部署许可条件：
```
K_t^cert ≥ 1/α_cert  ∧  K_t^rev < 1/α_rev  ∧  D_v(t)=0
∧ 体验约束成立  ∧  CE_t ≤ ε_ce  ∧  Triggers=∅.
```

**定义 125（体验感知的验证分配）**
验证动作集 `A_v`（仿真探针、现场抽检、用户询问、红队注入等）。动作 `a` 的期望信息增益 `ΔI(a;ρ)`（用 `E[Δ log K^cert]` 或后验方差下降近似），用户成本 `c_ux(a)`（打断+延迟），经济成本 `c(a)`。分配目标：
```
a* = argmax_{a∈A_v} (ΔI(a;ρ) - γ·c_ux(a)) / c(a)
     s.t. Σ c_ux(a) ≤ C_max^{ux},  Σ c(a) ≤ N_max.
```
并加覆盖约束：用户敏感动作区域至少获得 `q_min` 的验证预算份额。

**定义 126（体验-鲁棒性联合证书 `UXJ`）**
`UXJ = (J, U_S, K^cert, K^rev, T_½, B_v, evidence)`，其中 `J` 为第 54 轮联合证书。部署判定：
```
UXJ_ok ⇔ dom_J(T)=in ∧ δ_a<Θ_a ∧ U_S 满足体验约束
         ∧ K^cert≥1/α_cert ∧ K^rev<1/α_rev ∧ D_v=0 ∧ CE_t≤ε_ce.
```
证书失效不是二值的：`UXJ` 支持 `safe / pending / degraded / revoked` 四态，分别对应正常、欠租待复核、撤销检测报警、硬安全约束违反。

## 2. 关键算法伪代码

### IP-121 UXP（User Experience Profile）

```python
def ux_profile(traj, feedback, survey):
    lat = percentile(feedback.latency, 95)
    interrupt = feedback.interventions / max(1, traj.tasks)
    pred = 1.0 - entropy(traj.action_sequence) / log(len(traj.action_space))
    rec = mean(feedback.recovered_within(tau_rec))
    comp = mean(survey.comprehension_score)
    return UX(lat, interrupt, pred, rec, comp)

def trust_calibration(T, success_stream, eta=0.2):
    R = ema(success_stream, alpha=0.2)
    T_new = T + eta * (R - T)
    return T_new, abs(T_new - R), max(0.0, T_new - R)
```

### IP-122 ITV（Iterative Time-valid Validation）

```python
def itv_update(state, x, rho_min, alpha_cert=0.05, alpha_rev=0.05, k=0.05, h=6.0):
    state.logK_cert += log1p(state.lam_cert * (x - rho_min))
    state.logK_rev += log1p(state.lam_rev * (rho_min - x))
    state.cusum = max(0.0, state.cusum + (rho_min - x) - k)
    state.evidence.append(x)
    if exp(state.logK_cert) >= 1.0 / alpha_cert:
        state.status = 'safe'
    if state.cusum >= h or exp(state.logK_rev) >= 1.0 / alpha_rev:
        state.status = 'revoked'
        state.trigger = 'drift'
    return state
```

### IP-123 CIV（Counterexample-driven Iterative Validation）

```python
def counterexample_validation(state, explain, ux_sensitivity, budget):
    pool = explain.failures + explain.near_misses
    pool.sort(key=lambda c: c.severity * ux_sensitivity(c.region), reverse=True)
    for c in pool[:budget]:
        state = itv_update(state, int(c.success), rho_min)
        if c.ux_violation:
            state.trigger = 'ux'
            state.status = 'degraded'
    return state
```

### IP-124 UVA（UX-aware Validation Allocation）

```python
def allocate_validation(channels, state, B_v, gamma):
    best = None
    for a in channels:
        dI = expected_info_gain(a, state)          # E[d log K^cert] or variance drop
        c_ux = a.interrupt_cost + a.latency_cost
        score = (dI - gamma * c_ux) / max(a.cost, EPS)
        if best is None or score > best.score:
            best = Candidate(a, score)
    if best is None or best.score <= 0 or B_v.exhausted():
        return None                                # 宁可欠租待复核，也不疲劳轰炸用户
    return best.a
```

### IP-125 RGS（Revalidation Gate Scheduler）

```python
def revalidation_due(state, t, theta_u, eps_ce):
    state.n_eff *= exp(-state.lambda_d * (t - state.t_last))
    if state.n_eff < state.n_req:                 return 'half_life'
    if state.cusum >= state.h:                    return 'drift'
    if any(u < theta for u, theta in zip(state.U, theta_u)):
                                                   return 'ux'
    if abs(state.trust - state.reliability) > eps_ce:
                                                   return 'trust'
    return None
```

### IP-126 UXJ（UX-Joint Certificate）

```python
def ux_joint_certificate(J, U, state, theta_u, eps_ce):
    if J.domain != 'in' or J.delta_a >= Theta_a:
        return ('reject', 'action_mismatch')
    if not all(u >= theta for u, theta in zip(U, theta_u)):
        return ('reject', 'ux_violation')
    if state.status != 'safe' or state.cusum >= state.h:
        return ('reject', 'validation_not_valid')
    if abs(state.trust - state.reliability) > eps_ce:
        return ('reject', 'trust_miscalibrated')
    return ('ok', UXJ(J, U, state.evidence, state.T_half, state.B_v))
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| UXP | O(T + |A|) | O(1) | 反馈时延与打断统计无偏 |
| ITV | O(1)/样本，O(|Λ|)（对冲混合） | O(|Λ|) | λ 可预测、鞅性、Ville 界 |
| CIV | O(F log F + budget) | O(F) | 反例池覆盖、严重度排序 sound |
| UVA | O(|A_v|·|Λ|) | O(|A_v|) | VOI 单调、预算与覆盖约束 |
| RGS | O(1) | O(1) | 半衰期模型与漂移假设一致 |
| UXJ | O(|S|·|A| + |𝔇_ρ|) | O(|A| + |𝔇_ρ|) | 四态单调、硬约束优先 |

**正确性定理（Time-valid UX-aware Deployment Soundness）**
在承接第 53/54 轮 (A22)–(A28) 之外，假设：
**(A29)** 每个验证窗口内 `X_t` 相对历史可交换或漂移有界 `|p_t-p_{t-1}|≤ε_d`；
**(A30)** `U_S` 的多源测量与用户反馈无系统性选择偏差；
**(A31)** 信任更新为收缩映射，`CE_t` 可观测且 `ε_ce` 内可控。
则在整个部署期 `[0,H]` 内，发生“证书仍为 safe 但真实成功率已低于 `ρ_min`”的概率满足
```
P(unsafe while certified) ≤ α_cert + N_H·(α_rev + β_drift) + P(∃u: U_u<θ_u 未被检测),
```
其中 `N_H` 为重验证次数，`β_drift` 为变点检测在漂移强度 `ε_d` 下的漏检率。若 `D_v(t)>0` 时强制降为 `pending`，则上述界不再依赖“半衰期外仍有效”的隐含假设。

**关键推论**：`K^cert` 只能保证“未发现不安全”，不能保证“永远安全”；撤销能力由 `K^rev`/CUSUM 独立提供。把二者混为一个指标，是迭代验证最常见的统计错误。

## 4. 实验设计 E162–E166

| 实验 | 指标 | 目标 |
|---|---|---|
| E162 证书衰减 | 不同 `T_½` 下漂移后失败暴露时间 | 在 ≤1.5·`T_½` 内进入 pending/revoked |
| E163 撤销延迟 | 累积 e-process vs 分块 vs CUSUM 的延迟/误报 | CUSUM 中位延迟 ≤60 步，误报 ≤1% |
| E164 体验感知分配 | 单位用户打断捕获的危险事件数 | 比均匀分配提升 ≥30% |
| E165 信任校准 | `CE_t`、过度信任率、接管率 | `CE_t≤0.1`，过度信任率 ≤5% |
| E166 用户研究 | `UPS` vs task success、解释 P95 延迟、SUS | 解释 P95 ≤1s，UPS 与人工评分相关 ≥0.8 |

**E163 预实验结果（toy，2000 次重复，`ρ_min=0.85`，`p_pre=0.93`，漂移后 `p_post=0.72`，`t_drift=150`）**

| 方法 | 预漂移误报率 | 检出率 | 撤销延迟中位数 | P95 延迟 |
|---|---:|---:|---:|---:|
| 累积 e-process | 0.15% | 79.1% | 174 步 | 238 步 |
| 分块窗口（W=100，Bonferroni） | 0.00% | 96.0% | 149 步 | 249 步 |
| CUSUM（k=0.05, h=6） | 0.00% | 99.75% | **56 步** | **138 步** |

**读法**：累积 e-process 的“安全储蓄”使其撤销迟钝，分块窗口受窗口长度与 α 分摊拖累；CUSUM 在几乎不增加误报的前提下把撤销延迟压到 1/3。这直接支持“签发用 e-process、撤销用变点检测”的双时间尺度设计，也说明 `T_½` 不能取得过大，否则 `pending` 触发仍会滞后。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 漂移破坏可交换性，e-process 失效 | 高 | 有界漂移假设 + 短窗口重验 + 保守 α |
| 累积证书撤销延迟 | 高 | 双时间尺度（e-process + CUSUM）+ 半衰期强制复核 |
| UX 指标主观、可被讨好/博弈 | 高 | 多源测量 + 盲测 + 硬安全约束优先于 UX 优化 |
| 验证疲劳污染用户反馈 | 中 | VOI 预算、异步验证、覆盖约束、可拒绝询问 |
| 平滑解释诱发过度信任 | 高 | 过度信任绊线 + 强制失败演练 + 主动披露不确定 |
| 为 UX 牺牲安全 | 高 | 字典序约束：`domain`/`δ_a`/`K^rev` 为硬门槛，UX 只在可行域内优化 |

## 6. 本轮最大风险

**一句话**：本方案最大风险是：anytime-valid 证书与体验约束共同依赖“验证流可交换、用户反馈无偏、信任可校准”这三条强假设，一旦分布漂移与用户操控使它们同时失效，系统会用统计上“仍然有效”的证书为一个体验上已失控的部署背书；因此必须把撤销检测与硬安全约束置于证书之上，宁可频繁降级为 pending，也绝不把 anytime-valid 的“未拒绝”误读为“安全”。

# 第 55 轮产物 · 创新点清单 v32：GroundEdge-GenSim++++（UXP×ITV×CIV×UVA×RGS×UXJ）

> 承接第 54 轮产物 v31。本轮在动作-鲁棒性联合证书 `J` 之上，增加 **体验剖面、迭代验证、反例驱动、验证分配、重验证调度** 五个算子，把“一次性、任务中心”的证书升级为“有时间效力、以用户可感知成功为约束”的证书：
> - **UXP（User Experience Profile）**：技能体验剖面 `U_S`，把延迟/打断/可预测性/可恢复性/可理解性变成一等约束；
> - **ITV（Iterative Time-valid Validation）**：anytime-valid e-process + 撤销变点检测的双时间尺度验证；
> - **CIV（Counterexample-driven Iterative Validation）**：用第 54 轮 Explain 反例池驱动增量验证；
> - **UVA（UX-aware Validation Allocation）**：按单位用户成本的 VOI 分配验证预算；
> - **RGS（Revalidation Gate Scheduler）**：半衰期 + 漂移 + UX + 信任四类触发器的欠租复核；
> - **UXJ（UX-Joint Certificate）**：`强动作-鲁棒性证书 × 体验剖面 × 证据时钟` 的四元联合证书。

## 0. 核心 IP 设计

| 编号 | 名称 | 类型 | 关键改进 |
|---|---|---|---|
| IP-121 | UXP User Experience Profile | 新增 | 体验剖面 `U_S=(ℓ,ι,π,r,κ)`，约束用户感知成功 `UPS` |
| IP-122 | ITV Iterative Time-valid Validation | 新增 | `K^cert`/`K^rev` e-process + CUSUM 双时间尺度 |
| IP-123 | CIV Counterexample-driven Iterative Validation | 新增 | 反例池按 `severity×ux_sensitivity` 排序增量验证 |
| IP-124 | UVA UX-aware Validation Allocation | 新增 | `argmax (ΔI-γc_ux)/c`，含覆盖约束防验证疲劳 |
| IP-125 | RGS Revalidation Gate Scheduler | 新增 | 半衰期/漂移/UX/信任四触发器 + 欠债降级 |
| IP-126 | UXJ UX-Joint Certificate | 升级 IP-118 | `(J,U_S,K^cert,K^rev,T_½,B_v)` 四态证书 |

**与第 54 轮的关系**：第 54 轮回答“组合在动作空间与鲁棒性上是否可行”；本轮回答“这张组合证书在时间上是否仍有效、对用户是否仍可用”。`UXJ` 不替代 `J`，而是在 `J` 的可行域内叠加证据时钟与体验门槛；`J` 不可行时，任何验证预算都不应被消耗。

## 2. 关键算法伪代码

### IP-121 UXP

```python
def ux_profile(traj, feedback, survey):
    lat = percentile(feedback.latency, 95)
    interrupt = feedback.interventions / max(1, traj.tasks)
    pred = 1.0 - entropy(traj.action_sequence) / log(len(traj.action_space))
    rec = mean(feedback.recovered_within(tau_rec))
    comp = mean(survey.comprehension_score)
    return UX(lat, interrupt, pred, rec, comp)

def experience_ok(U, theta):
    return all(u >= t for u, t in zip(U, theta))

def trust_calibration(T, success_stream, eta=0.2):
    R = ema(success_stream, alpha=0.2)
    T_new = T + eta * (R - T)
    return T_new, abs(T_new - R), max(0.0, T_new - R)
```

### IP-122 ITV

```python
def itv_update(state, x, rho_min, alpha_cert=0.05, alpha_rev=0.05, k=0.05, h=6.0):
    state.logK_cert += log1p(state.lam_cert * (x - rho_min))
    state.logK_rev += log1p(state.lam_rev * (rho_min - x))
    state.cusum = max(0.0, state.cusum + (rho_min - x) - k)
    state.evidence.append(x)
    state.status = 'pending' if state.debt > 0 else state.status
    if exp(state.logK_cert) >= 1.0 / alpha_cert:
        state.status = 'safe'
    if state.cusum >= h or exp(state.logK_rev) >= 1.0 / alpha_rev:
        state.status = 'revoked'
        state.trigger = 'drift'
    return state
```

> 说明：实现时 `K^cert` 用 `λ` 网格的对冲混合（hedged capital），每个分量在 `H_0` 下是超鞅，混合后仍超鞅，因此任意时刻看结果都合法。

### IP-123 CIV

```python
def counterexample_validation(state, explain, ux_sensitivity, budget):
    pool = explain.failures + explain.near_misses
    pool.sort(key=lambda c: c.severity * ux_sensitivity(c.region), reverse=True)
    for c in pool[:budget]:
        state = itv_update(state, int(c.success), rho_min)
        if c.ux_violation:
            state.trigger = 'ux'
            state.status = 'degraded'
        if state.status in ('degraded', 'revoked'):
            break
    return state
```

### IP-124 UVA

```python
def allocate_validation(channels, state, B_v, gamma, q_min):
    covered = {a.region for a in state.validated_regions}
    for a in channels:
        a.score = (expected_info_gain(a, state) - gamma * (a.interrupt_cost + a.latency_cost)) / max(a.cost, EPS)
        if a.region not in covered:
            a.score += q_min_bonus
    feas = [a for a in channels if B_v.allows(a)]
    if not feas:
        return None
    best = max(feas, key=lambda a: a.score)
    return best if best.score > 0 else None
```

### IP-125 RGS

```python
def revalidation_due(state, t, theta_u, eps_ce):
    state.n_eff *= exp(-state.lambda_d * (t - state.t_last))
    state.debt = max(0.0, state.n_req - state.n_eff)
    if state.debt > 0:                                  return 'half_life'
    if state.cusum >= state.h:                          return 'drift'
    if not experience_ok(state.U, theta_u):             return 'ux'
    if abs(state.trust - state.reliability) > eps_ce:   return 'trust'
    return None
```

### IP-126 UXJ

```python
def ux_joint_certificate(J, U, state, theta_u, eps_ce):
    if J.domain != 'in' or J.delta_a >= Theta_a:
        return ('reject', 'action_mismatch')
    if not experience_ok(U, theta_u):
        return ('reject', 'ux_violation')
    if state.status in ('degraded', 'revoked') or state.cusum >= state.h:
        return ('reject', 'validation_not_valid')
    if state.debt > 0 or state.status == 'pending':
        return ('reject', 'validation_debt')
    if abs(state.trust - state.reliability) > eps_ce:
        return ('reject', 'trust_miscalibrated')
    return ('ok', UXJ(J, U, state.evidence, state.T_half, state.B_v), 'safe')
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| UXP | O(T+|A|) | O(1) | 延迟/打断统计无偏，盲测理解度 |
| ITV | O(1)/样本，O(|Λ|) 对冲 | O(|Λ|) | λ 可预测，Ville 任意停时界 |
| CIV | O(F log F + budget) | O(F) | 反例池覆盖、严重度排序 sound |
| UVA | O(|A_v|·|Λ|) | O(|A_v|) | VOI 单调、预算/覆盖约束可行 |
| RGS | O(1) | O(1) | 半衰期模型与漂移有界假设一致 |
| UXJ | O(|S|·|A|+|𝔇_ρ|) | O(|A|+|𝔇_ρ|) | 四态单调、硬约束优先 |

**正确性定理（Time-valid UX-aware Deployment Soundness）**
承接 (A22)–(A28)，并假设：
**(A29)** 每个验证窗口内证据相对历史可交换，或漂移有界 `|p_t-p_{t-1}|≤ε_d`；
**(A30)** `U_S` 的多源测量与用户反馈无系统性选择偏差；
**(A31)** 信任更新为收缩映射，`CE_t` 可观测。
则部署期 `[0,H]` 内“证书仍为 safe 但真实成功率低于 `ρ_min`”的概率满足
```
P(unsafe while certified) ≤ α_cert + N_H·(α_rev + β_drift) + P(UX 约束违反未被检测),
```
其中 `N_H` 为重验证次数，`β_drift=β_drift(ε_d)` 为变点漏检率。若 `D_v>0` 时强制降为 `pending` 且禁止新任务组合，则上界不依赖“半衰期外仍有效”的隐含假设。

**三条可伪证推论**
1. 若在强非平稳流上累积 `K^cert` 仍长期为 safe，而 CUSUM 已报警，则说明“未拒绝≠安全”，应优先信撤销通道。
2. 若 UX-aware 分配相对均匀分配没有提高“单位用户打断捕获的危险事件数”，则 `ΔI` 代理失效，UVA 应退回均匀/分层采样。
3. 若 `T_½` 增大不改变失效暴露时间，说明漂移不是主因，应重查动作剖面与云边映射，而非继续加验证预算。

**E163 预实验（toy，2000 次重复；`ρ_min=0.85`，`p_pre=0.93`，`p_post=0.72`，`t_drift=150`；`α=0.05`）**

| 方法 | 预漂移误报率 | 检出率 | 撤销延迟中位数 | P95 延迟 |
|---|---:|---:|---:|---:|
| 累积 e-process（对冲 λ 网格） | 0.15% | 79.10% | 174 步 | 238 步 |

**结论**：累积 anytime-valid 证据适合“签发/维持”，但其撤销延迟随安全历史增长；必须并联一个快速变点检测，并把 `T_½` 纳入部署状态机。复现脚本：`exp/v55/itv_ux_sim.py`，结果：`exp/v55/itv_ux_sim_results.json`。

## 6. 本轮最大风险

**一句话**：本方案最大风险是：anytime-valid 证书与体验约束共同依赖“验证流可交换、用户反馈无偏、信任可校准”这三条强假设，一旦分布漂移与用户操控使它们同时失效，系统会用统计上“仍然有效”的证书为一个体验上已失控的部署背书；因此必须把撤销检测与硬安全约束置于证书之上，宁可频繁降级为 pending，也绝不把 anytime-valid 的“未拒绝”误读为“安全”。
