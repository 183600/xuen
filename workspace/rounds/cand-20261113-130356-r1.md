## 0. 直觉与动机

**灵感 1（中间件 → 安全语义的实际执行者）**
直觉：很多工作把安全放在算法层，把中间件当作「把消息送到就行」的透明层。但安全的最后一公里恰恰发生在中间件：一条 deadline 消息被 DDS 丢掉、一个语义节点因降频而晚 200ms 唤醒、一次图像压缩把故障残差抹平——算法证书本身没错，是**证书的传输与调度把它变成了过期结论**。中间件掌握 `QoS(reliability, deadline, lifespan)`、executor 线程分配、零拷贝开关、节点 lifecycle 与 DVFS 档位，因此它是唯一能对「安全结论的新鲜度」负责的层。换句话说：**中间件不生产安全，但它决定安全结论能不能准时到达。**

**灵感 2（能耗优化 → 证书是易腐品，刷新是一笔投资）**
直觉：把证书看成生鲜：刚出炉时价值最高，随时间指数衰减；刷新它要花一笔焦耳。于是「省电」不是一个独立目标，而是一个**投资组合问题**：把有限的能量预算投给「单位焦耳能挽回最多风险」的证书。这个边际量就是「安全的焦耳影子价格」`μ`——当电池紧张时 `μ` 上升，只有最关键的证书还配得上刷新；当电量充裕时 `μ` 下降，连低风险证书也可保持新鲜。这把能耗优化与安全证书统一进同一个拉格朗日乘子里。

**灵感 3（动作分块 → 计算-执行功率协同）**
直觉：电池的痛点往往不是平均能耗，而是**峰值功率**：机械臂加速瞬间的大电流会造成电压跌落、热堆积与效率下降，随后触发降频，反而拖慢语义推理。VISTA/ACH 的动作分块天然提供了未来 `H` 步的执行器功率前瞻 `p̂_act(t)`。于是中间件可以做一件此前没人做的事：**把重的语义计算搬进低转矩的「功率山谷」**，在不推迟任何证书 deadline 的前提下削平总功率峰值。这是「运动感知的计算调度」：运动计划不只是被执行的轨迹，也是中间件的**能耗时刻表**。

**灵感 4（刷新排程 →  restless bandit 与 Whittle 指数）**
直觉：每张证书都有自己的「年龄」`a_i`，不刷新就线性变老、风险单调上升；刷新则回到 0 岁并消耗 `c_i` 焦耳；所有证书共享一个平均功率预算。这正是** restless multi-armed bandit（RMAB）**：每支臂的状态（年龄）即使不被拉动也在演化。在可指数化（indexability）条件下，Whittle 指数给出一个极简的阈值策略——**当某证书的「单位焦耳风险削减」超过影子价格 `μ` 时就刷新它**。`μ` 由预算的拉格朗日对偶唯一确定。于是复杂的跨层能耗调度退化成一个可解释的、可预计算的阈值表。

**灵感 5（五灵感合流 → WATT）**
WATT 在 RAS 的「语义-安全」两率架构上再插入一条**能量账本**：
1. **EML Energy-Middleware Ledger**：按组件记录每次推理/传输/盾计算的焦耳，形成可审计账本；
2. **EPS Energy-Priced Certificate**：证书附带 `(E_cost, h, a_max)`，把「新鲜度」变成可交易量；
3. **WRA Whittle Refresh Arbiter**：以 `μ` 为阈值决定刷新哪张证书；
4. **PCS Power Co-Scheduler**：用动作块前瞻做计算-执行峰值削峰；
5. **EAQ Energy-Aware QoS**：在 `(rate, compression, precision, offload)` 上做能量-失真-时延的跨层协商；
6. **ESH Energy-Aware Safety Shield**：功率受限时按风险后验优先级保约束，最坏退化为低功耗安全停；
7. **DGL Degradation Ladder**：能量耗尽时的有序降级阶梯；
8. **TEC Thermal-Energy Coupler**：把热节流反馈进语义时延与预算；
9. **J_WATT**：把能量账本、影子价格、新鲜度向量写进证书，使「安全」可复现、可审计。

## 1. 形式化定义（增量：定义 245–258）

- **定义 245（WATT 总览）**：WATT = (EML, EPS, WRA, PCS, EAQ, ESH, DGL, TEC, J_WATT)。定位：VISTA 的「故障闭环」与 RAS 的「意图闭环」共享的**能量底座**。不变式：(i) 中间件只调度、不写学习状态；(ii) 最高风险后验的证书拥有不可剥夺的保留预算；(iii) 任何降级只能沿 DGL 单向下降，禁止「省电导致的静默越过安全边界」。
- **定义 246（能耗分解）**：在时间窗 `[0,T]` 上
  `E_total = E_act + E_sem + E_comm + E_rt + E_leak + E_aux`，
  其中中间件可控部分为 `E_mw = E_sem + E_comm + E_rt`；瞬时功率 `P_total(t) = dE_total/dt`。`E_act` 由执行器/运动计划决定，`E_leak + E_aux` 为不可控底噪。
- **定义 247（证书能量价格）**：对证书 `κ`，`E_cost(κ, q)` 为在质量档 `q` 下产出该证书的焦耳数；`h_κ` 为新鲜度半衰期；`V_κ(a)` 为证书年龄 `a` 时仍能挽回的风险期望。定义**单位焦耳安全价值**
  `ε_κ(a) = V_κ(a) / E_cost(κ, q)`。
- **定义 248（证书年龄与陈旧风险）**：`a_i(t) = t - t_last,i`；陈旧风险
  `R_stale,i(a) = R_i^∞ · (1 - exp(-a/h_i))`，
  `R_i^∞` 为该证书完全过期时的风险上界。证书有效当且仅当 `a_i < a_max,i`。`R_stale,i` 关于 `a` 单调不减。
- **定义 249（能耗预算下的刷新调度）**：离散时隙 `Δ` 上，状态 `a_i ∈ {0,...,A_i^max}`；刷新动作使 `a_i ← 0` 并支付 `c_i = E_cost,i` 焦耳，否则 `a_i ← a_i + 1`。目标
  `min_π  J(π) = E_π[ Σ_t Σ_i R_stale,i(a_i(t)) ]`
  受约束 `E_π[ Σ_t Σ_i c_i · 1{refresh i at t} ] ≤ \bar P · T`。这是一个带能量约束的 restless bandit。
- **定义 250（Whittle 指数与焦耳影子价格）**：`w_i(a)` 为「在年龄 `a` 刷新臂 `i`」相对于「不刷新」的边际风险削减除以 `c_i`，即使得两动作在带补贴 `m` 的松弛问题中无差异的补贴值。在线策略：
  `refresh i  ⇔  w_i(a_i) ≥ μ`，
  其中 `μ` 为能量约束的拉格朗日乘子，由 `Σ_i rate_i(μ)·c_i = \bar P` 唯一确定。经济学解释：`μ` 是**安全的焦耳影子价格**。
- **定义 251（动作-计算功率协同）**：设动作块给出执行器功率前瞻 `p̂_act(t), t ∈ [t, t+H]`，证书刷新窗口为 `[d_i - slack_i, d_i]`。协同调度问题：
  `min_{s_i ∈ [d_i-slack_i, d_i]}  max_{t} [ p̂_act(t) + p_mw(t; {s_i}) ]`
  受「刷新时刻落在窗口内」约束。即在不改变任何证书 deadline 的前提下，把计算功率填进 `p̂_act` 的谷底（valley filling）。
- **定义 252（能量感知 CBF 盾）**：设 `π_i` 为 VISTA/RAS 联合后验导出的故障-风险质量。ESH 在每个控制周期解
  `u* = argmin_u ||u - u_ref||²`
  `s.t.  h_k(x_{t+1}) ≥ (1-γ) h_k(x_t),  k ∈ TopK(π)`
  `      P_total(t) ≤ \bar P_peak`。
  若 QP 不可行，则输出 `u_safe`（低功耗安全停/最小制动），并记录一次 `power_infeasible` 事件。
- **定义 253（热-能-时延耦合）**：一阶 RC 热模型
  `C_th · dT/dt = P_total(t) - (T(t) - T_amb)/R_th`。
  温度通过 DVFS 映射 `f_T(T) ∈ (0,1]` 调制计算频率，语义时延
  `L_sem(T) = L_sem^0 / f_T(T)`。因此「省电」若以热峰值为代价，会反向拉长语义时延、增加证书陈旧风险。
- **定义 254（能量-新鲜度可达域 EFR）**：给定预算 `\bar P` 与时间窗 `T`，定义可达的证书年龄-质量向量集合
  `FR(\bar P) = { (a_i, q_i) : ∃π 满足预算且 E[a_i] ≤ a_i, q_i ≤ q_i^max }`。
  EFR 的帕累托前沿即「在此电池下安全能做到多新鲜」。`μ` 是前沿的切线斜率。
- **定义 255（EAQ 跨层 QoS）**：中间件为每个语义流选择四元组 `(r, κ_c, q, o)`（刷新率、压缩率、推理精度、本地/边缘卸载），求解
  `min E_mw  s.t.  D(r,κ_c,q,o) ≤ D_max,  L(r,κ_c,q,o) ≤ deadline,  o ∈ {local, edge}`。
  其中 `D` 为语义失真，卸载项额外计入通信能量与链路时延。
- **定义 256（DGL 分级降级阶梯）**：状态 `P0`（全量）→ `P1`（停非关键语义）→ `P2`（降故障归因频率）→ `P3`（低功耗安全停）。状态转移仅允许在剩余能量低于阈值 `b_k` 或热预算越界时向下降一级；并强制约束：**任何时刻被丢弃的证书，其风险质量不得高于被保留证书**。
- **定义 257（J_WATT 证书）**：`J_WATT = (J_vista, J_RAS, ledger_digest, μ, freshness_vec, thermal_headroom, eaq_profile, watt_ver)`。`Valid ⇔ Valid(J_vista) ∧ Valid(J_RAS) ∧ (∀i ∈ Critical: a_i < a_max,i) ∧ (ledger_digest 可复算) ∧ (μ ≤ μ_max)`。
- **定义 258（可审计能量账本 EML）**：只追加记录 `ℓ_k = (component, e_k, t_k, q_k, cert_hash_k)`，满足 `Σ e_k` 与外部电池计一致（容差 `ε_E`）。账本用于复算 `μ`、检测「计价漂移」与中间件被篡改/失准的攻击面。

# IP-234 EML：按组件记账，拒绝无来源的能量黑洞
class EnergyMiddlewareLedger:
    def __init__(self):
        self.entries = []
        self.component_energy = defaultdict(float)

    def record(self, component, joules, quality, cert_hash):
        e = {'component': component, 'joules': joules, 'quality': quality,
             'cert_hash': cert_hash, 't': now()}
        self.entries.append(e)
        self.component_energy[component] += joules

    def digest(self):
        return sha256(canonical_json(self.entries)).hexdigest()

    def reconcile(self, battery_delta, tol=0.05):
        return abs(sum(self.component_energy.values()) - battery_delta) <= tol * battery_delta


# IP-235/236：证书年龄、能量价格与 Whittle 刷新仲裁
class EnergyPricedCertificate:
    def __init__(self, cid, e_cost, half_life, a_max, r_inf):
        self.cid, self.e_cost = cid, e_cost
        self.h, self.a_max, self.r_inf = half_life, a_max, r_inf

    def age(self, t):
        return t - self.last_refresh

    def stale_risk(self, a):
        return self.r_inf * (1.0 - math.exp(-a / self.h))

    def value(self, a):
        return self.r_inf * math.exp(-a / self.h)   # V(a) = -dR/da 的近似


class WhittleRefreshArbiter:
    def __init__(self, certs, whittle_table, p_budget):
        self.certs = certs
        self.w = whittle_table      # w[i][a]，离线预计算
        self.mu = solve_mu(certs, whittle_table, p_budget)  # 二分求影子价格

    def choose(self, t):
        due = []
        for c in self.certs:
            a = c.age(t)
            if a >= c.a_max:
                due.append(c)                       # 硬 deadline，必须刷新
            elif self.w[c.cid][a] >= self.mu:       # 单位焦耳价值超阈值
                due.append(c)
        return due

    def solve_mu(self, certs, w, p_budget):
        lo, hi = 0.0, 1e9
        for _ in range(64):
            mu = 0.5 * (lo + hi)
            used = sum(c.e_cost / expected_cycle(c.cid, w, mu) for c in certs)
            if used <= p_budget:
                hi = mu          # 预算够 → 影子价格可降
            else:
                lo = mu
        return hi


# IP-237：用动作块前瞻把计算填进功率山谷
def power_co_schedule(certs, p_act_forecast, horizon, dt):
    windows = [(max(0, c.deadline - c.slack), c.deadline) for c in certs]
    slots = np.arange(0, horizon, dt)
    p_mw = np.zeros_like(slots)
    for c, (lo, hi) in zip(certs, windows):
        idx = [i for i, t in enumerate(slots) if lo <= t <= hi]
        j = min(idx, key=lambda i: p_act_forecast[i] + p_mw[i])  # 谷底
        p_mw[j] += c.e_cost / dt
    peak = np.max(p_act_forecast + p_mw)
    return slots, p_mw, peak, all(lo <= slots[np.argmax(p_mw > 0)] <= hi
                                  for (_, (lo, hi)) in zip(certs, windows))


# IP-239：按风险后验优先级保约束的能量感知盾
def energy_aware_shield(x, u_ref, hypotheses, p_budget, gamma=0.1):
    topk = sorted(hypotheses, key=lambda h: h.posterior, reverse=True)[:K]
    qp = build_cbf_qp(x, u_ref, topk, gamma)
    qp.add_power_constraint(p_budget)
    try:
        return qp.solve()
    except Infeasible:
        log_event('power_infeasible', topk[0].posterior)
        return safe_stop_low_power(x)   # 最低功耗、可证安全


# IP-240：有序降级（风险高的证书最后被饿死）
def degradation_step(state, budget_left, thermal_headroom):
    if budget_left < state.b[3] or thermal_headroom <= 0:
        state.level = max(state.level, 3)
    elif budget_left < state.b[2]:
        state.level = max(state.level, 2)
    elif budget_left < state.b[1]:
        state.level = max(state.level, 1)
    assert_never_starve_highest_risk(state)   # 不变量
    return state


# IP-242：WATT 主循环
def WATT_round(M, obs, t):
    V, T, P, L, P_cloud, W_meas, tactile, img, depth, flow = obs
    p_act_forecast = M.vista.ach.power_forecast(H=M.horizon)   # 动作块前瞻

    # 1) 语义层产出带能量价格的证书（只在语义流）
    certs = M.semantic.issue_certificates(obs, quality=M.eaq.current_quality())
    for c in certs:
        M.ledger.record(c.component, c.e_cost, c.quality, c.hash)

    # 2) 热-能耦合：更新可用预算与降级阶梯
    M.tec.update(p_act_forecast, M.ledger)
    M.dgl = degradation_step(M.dgl, M.tec.budget_left, M.tec.headroom)

    # 3) WRA：以影子价格 μ 选择刷新
    refresh = M.wra.choose(t)

    # 4) PCS：把刷新计算移入功率山谷（不改 deadline）
    slots, p_mw, peak, ok = power_co_schedule(refresh, p_act_forecast,
                                              M.horizon, M.dt)
    assert ok or M.dgl.level >= 2

    # 5) 实时层：能量感知盾
    hyps = M.vista.fir.attribute(M.vista.residual_log) + M.ras.emotion_hypotheses
    u = energy_aware_shield(M.x, M.u_ref, hyps, M.tec.p_peak)

    # 6) 复查账本并签发 WATT 证书
    M.ledger.reconcile(M.battery.delta())
    J = M.watt_cert.issue(M.vista.cert, M.ras.cert, M.ledger.digest(),
                          M.wra.mu, M.wra.freshness(), M.tec.headroom)
    return u, J, M.wra.mu

## 3. 推导

**引理 11（Whittle 阈值策略的渐近最优性）** 设各证书的年龄过程相互独立、满足 indexability，且刷新成本有界。则在能量预算 `\bar P` 下，由定义 250 给出的阈值策略满足
`(1/T)·J(π_WATT) ≤ (1/T)·J(π*) + O(1/√N)`（`N` 为证书数）在流体极限下成立；`μ` 收敛到预算约束的对偶变量。**直觉**：这是 restless bandit 的经典结论在「证书刷新」上的落地；`μ` 不是拍脑袋的参数，而是能量约束的影子价格。

**引理 12（峰值削峰不增加陈旧度）** 若协同调度只把刷新时刻限制在各自窗口 `[d_i-slack_i, d_i]` 内重新分配，则所有证书的 deadline 不变，故 `a_i < a_max,i` 的可行性不变；而 `max_t p_total(t)` 不增（取原调度为可行解，故最优值 ≤ 原峰值）。**推论**：削峰可以「免费」获得，只要 `slack_i ≥ 0`。

**引理 13（热耦合的必要性）** 若调度忽略 `f_T(T) < 1`，则真实语义时延被低估为 `L_sem^0`，而实际为 `L_sem^0/f_T(T)`。因此忽略热耦合会把 `a_i` 低估至少 `(1/f_T(T) - 1)·L_sem^0`，从而使 `R_stale` 低估。**推论**：能量预算必须扣除热裕度，否则「热节流」会以陈旧证书的形式变成安全故障。

**定理 11（WATT 端到端安全-能量一致性）** 在 A92–A96（证书风险单调、预算可行、账本诚实、热模型一阶匹配、盾的 QP 可行域非空）下，WATT 输出的控制指令满足
1. `P(违规) ≤ α_chunk + δ_fi + δ_RAS + α_energy`，其中 `α_energy = Σ_i P(a_i ≥ a_max,i)` 为能量饥饿导致的陈旧概率；
2. `E[E_total] ≤ \bar P·T·(1+ε_E)`（账本对账容差）；
3. 若 `P_total` 触顶且 QP 不可行，则系统进入 `P3` 安全停，且该转移**不依赖**任何语义推理结果（即不依赖可能过期的证书）。

**定理 12（有序降级的安全性）** 在账本诚实且风险质量 `π_i` 正确的条件下，DGL 保证：当预算 `B → 0` 时，被饿死的证书按风险质量从低到高依次发生，最高风险证书最后失去刷新；系统最终收敛到最低功耗的认证安全停，而不会停在「省电但危险」的中间态。**要点**：这排除了「把安全预算省成事故」的均衡。

**定理 13（能量-安全不可约性 / 无免费午餐）** 在 EFR 前沿上，安全裕度对能量预算的边际收益等于影子价格：
`dS*/d\bar P = μ ≥ 0`。
因此不存在同时达到「零陈旧」与「最小能量」的策略；任何声称两者兼得的方案，必然把成本转移到了未计入的维度（热、峰值电流或证书质量）。这为 WATT 的预算-安全权衡提供了不可约的下界解释。

## 6. 本轮最大风险

**一句话**：WATT 把「安全」折算成「焦耳影子价格 `μ`」并以中间件为唯一仲裁者，但一旦能耗账本失准、热模型失配或中间件被篡改，`μ` 会被系统性低估，系统就会**高效地、静默地饿死最关键的证书**——它不会报错，只会「省电地把安全边界一点点让出去」，这是比单次故障更危险的失效模式：**优化器本身成了安全边界的最优破坏者。**

**定义 245（WATT 总览）**
```
WATT = (EML, EPS, WRA, PCS, EAQ, ESH, DGL, TEC, J_WATT)
```
不变式：(i) 中间件只调度、不写学习状态；(ii) 最高风险后验的证书拥有不可剥夺的保留预算；(iii) 降级只能沿 DGL 单向下降。

**定义 246（能耗分解）**
```
E_total = E_act + E_sem + E_comm + E_rt + E_leak + E_aux,
P_total(t) = dE_total/dt,   E_mw = E_sem + E_comm + E_rt.
```

**定义 247（证书能量价格）**
```
ε_κ(a) = V_κ(a) / E_cost(κ, q)
```
其中 `V_κ(a)` 为年龄 `a` 时证书仍能挽回的风险期望。

**定义 248（证书年龄与陈旧风险）**
```
a_i(t) = t - t_last,i
R_stale,i(a) = R_i^∞ · (1 - exp(-a / h_i))
```
证书有效当且仅当 `a_i < a_max,i`；`R_stale,i` 关于 `a` 单调不减。

**定义 249（能耗预算下的刷新调度）**
```
min_π  E_π[ Σ_t Σ_i R_stale,i(a_i(t)) ]
s.t.   E_π[ Σ_t Σ_i c_i · 1{refresh i at t} ] ≤ \bar P · T,
       a_i ∈ {0,...,A_i^max},  c_i = E_cost,i.
```
这是一个带能量约束的 restless bandit。

**定义 250（Whittle 指数与焦耳影子价格）**
```
refresh i  ⇔  w_i(a_i) ≥ μ,
Σ_i rate_i(μ) · c_i = \bar P.
```
`w_i(a)` 是年龄 `a` 刷新臂 `i` 相对不刷新的「单位焦耳边际风险削减」；`μ` 是预算约束的拉格朗日乘子，即安全的焦耳影子价格。

**定义 251（动作-计算功率协同）**
```
min_{s_i ∈ [d_i-slack_i, d_i]}  max_t [ p̂_act(t) + p_mw(t; {s_i}) ]
```
在不改变任何证书 deadline 的前提下，把计算功率填入执行器功率谷底。

**定义 252（能量感知 CBF 盾）**
```
u* = argmin_u ||u - u_ref||²
s.t. h_k(x_{t+1}) ≥ (1-γ) h_k(x_t),  k ∈ TopK(π)
     P_total(t) ≤ \bar P_peak
```
不可行时输出 `u_safe`（低功耗安全停）并记录 `power_infeasible`。

**定义 253（热-能-时延耦合）**
```
C_th · dT/dt = P_total(t) - (T(t) - T_amb)/R_th
L_sem(T) = L_sem^0 / f_T(T),  f_T(T) ∈ (0,1].
```

**定义 254（能量-新鲜度可达域 EFR）**
```
FR(\bar P) = { (a_i, q_i) : ∃π 满足预算且 E[a_i] ≤ a_i, q_i ≤ q_i^max }.
```
其帕累托前沿即「此电池下安全能做到多新鲜」；`μ` 为前沿切线斜率。

min E_mw  s.t. D(r,κ_c,q,o) ≤ D_max, L(r,κ_c,q,o) ≤ deadline

`o ∈ {local, edge}`，卸载额外计入通信能量与链路时延。

# ---------- IP-234 EML ----------
class EnergyMiddlewareLedger:
    def record(self, component, joules, quality, cert_hash):
        self.entries.append(dict(component=component, joules=joules,
                                 quality=quality, cert_hash=cert_hash, t=now()))
        self.component_energy[component] += joules

    def digest(self):
        return sha256(canonical_json(self.entries)).hexdigest()

    def reconcile(self, battery_delta, tol=0.05):
        return abs(sum(self.component_energy.values()) - battery_delta) <= tol * battery_delta


# ---------- IP-235 / IP-236 EPS + WRA ----------
class EnergyPricedCertificate:
    def __init__(self, cid, e_cost, half_life, a_max, r_inf):
        self.cid, self.e_cost = cid, e_cost
        self.h, self.a_max, self.r_inf = half_life, a_max, r_inf
        self.last_refresh = now()

    def age(self, t):            return t - self.last_refresh
    def stale_risk(self, a):     return self.r_inf * (1.0 - math.exp(-a / self.h))
    def value(self, a):          return self.r_inf * math.exp(-a / self.h)


class WhittleRefreshArbiter:
    def __init__(self, certs, whittle_table, p_budget):
        self.certs, self.w = certs, whittle_table
        self.mu = self.solve_mu(p_budget)

    def solve_mu(self, p_budget):
        lo, hi = 0.0, 1e9
        for _ in range(64):
            mu = 0.5 * (lo + hi)
            used = sum(c.e_cost / expected_cycle(c.cid, self.w, mu)
                       for c in self.certs)
            if used <= p_budget: hi = mu
            else:                lo = mu
        return hi

    def choose(self, t):
        return [c for c in self.certs
                if c.age(t) >= c.a_max                 # 硬 deadline
                or self.w[c.cid][c.age(t)] >= self.mu] # 影子价格阈值


# ---------- IP-237 PCS ----------
def power_co_schedule(certs, p_act_forecast, horizon, dt):
    slots = np.arange(0, horizon, dt)
    p_mw  = np.zeros_like(slots)
    for c in certs:
        lo, hi = c.deadline - c.slack, c.deadline
        idx = np.where((slots >= lo) & (slots <= hi))[0]
        j = idx[np.argmin(p_act_forecast[idx] + p_mw[idx])]   # 谷底
        p_mw[j] += c.e_cost / dt
    return slots, p_mw, float(np.max(p_act_forecast + p_mw))


# ---------- IP-239 ESH ----------
def energy_aware_shield(x, u_ref, hypotheses, p_budget, gamma=0.1, K=3):
    topk = sorted(hypotheses, key=lambda h: h.posterior, reverse=True)[:K]
    qp = build_cbf_qp(x, u_ref, topk, gamma)
    qp.add_power_constraint(p_budget)
    try:
        return qp.solve()
    except Infeasible:
        log_event('power_infeasible', topk[0].posterior)
        return safe_stop_low_power(x)

def degradation_step(state, budget_left, headroom):
    if budget_left < state.b[3] or headroom <= 0: state.level = max(state.level, 3)
    elif budget_left < state.b[2]:                state.level = max(state.level, 2)

## 4. 推导

**引理 11（Whittle 阈值策略的渐近最优性）** 在 indexability 与独立年龄过程假设下，阈值策略 `w_i(a_i) ≥ μ` 的长期平均风险满足
```
(1/T) J(π_WATT) ≤ (1/T) J(π*) + O(1/√N),
```
且 `μ` 收敛到预算约束的对偶变量。**含义**：`μ` 是可解释、可预计算的「安全焦耳价格」，而非手调超参。

**引理 12（峰值削峰不增加陈旧度）** 协同调度只在各证书的 `[d_i-slack_i, d_i]` 内重排刷新时刻，deadline 集合不变，故 `a_i < a_max,i` 可行性不变；且原调度是可行解，故 `max_t p_total` 的最优值不超过原峰值。

**引理 13（热耦合的必要性）** 忽略 `f_T(T)<1` 会把语义时延低估为 `L_sem^0`，实际为 `L_sem^0/f_T(T)`，从而低估 `a_i` 至少 `(1/f_T(T)-1)L_sem^0`，进而低估 `R_stale`。**含义**：省电若制造热峰，会以陈旧证书的形式反噬安全。

**定理 11（WATT 端到端安全-能量一致性）** 在 A92–A96 下：
1. `P(违规) ≤ α_chunk + δ_fi + δ_RAS + α_energy`，其中 `α_energy = Σ_i P(a_i ≥ a_max,i)`；
2. `E[E_total] ≤ \bar P·T·(1+ε_E)`；
3. `P_total` 触顶且 QP 不可行 ⇒ 进入 `P3` 安全停，且该转移不依赖任何可能过期的语义证书。

**定理 12（有序降级的安全性）** 在账本诚实、风险质量正确的条件下，`B → 0` 时被饿死的证书按风险质量从低到高发生，最高风险证书最后失去刷新，系统收敛到最低功耗的认证安全停，而非「省电但危险」的中间态。

**定理 13（能量-安全不可约性）** 在 EFR 前沿上 `dS*/d\bar P = μ ≥ 0`。故不存在同时达到「零陈旧」与「最小能量」的策略；任何声称兼得的方案，都把成本转移到了未计入的维度（热、峰值电流或证书质量）。

## 6. 实验设计 E251–E260

| 实验 | 关键问题 | 目标 |
|---|---|---|
| E251 EML账本精度 | 组件级能耗可归因 | 与功率计误差 < 5%，漏记 = 0 |
| E252 WRA vs 固定频率 | 同安全下省电 | `E_mw` 降 25–35%，陈旧风险不变 |
| E253 PCS削峰 | 计算-执行协同 | 峰值降 20–30%，deadline 违约 = 0 |
| E254 TEC热耦合 | 热节流诱发的隐性陈旧 | 有 TEC 时违规 = 0；无 TEC 对照 ≥ 5% |
| E255 ESH盾 | 功率受限下安全不变量 | 违规 ≤ 基线；不可行时 100% 安全停 |
| E256 DGL有序降级 | 预算耗尽时谁先被丢 | 高风险证书饥饿 = 0；停态可证安全 |
| E257 端到端WATT | 安全不降、能耗下降 | 成功率持平，总能耗降 20–30% |
| E258 账本攻击/漂移 | 中间件失准可检出 | 5% 漂移检出 ≥ 95%，误报 < 2% |
| E259 中间件实时性 | 调度开销 | < 100µs，jitter 不越界 |
| E260 平台迁移 | 电池/嵌入式可部署 | Jetson+ROS2 上 `E_mw` 降 ≥ 15% |

**消融**：去掉 WRA / PCS / TEC / DGL，分别验证其对「安全-能量」帕累托前沿的独立贡献。**预注册失败判据**：E252 等安全下节能 < 10%，或 E255 出现任何「QP 不可行但未安全停」事件，则 WATT 的核心假设（证书风险可加、预算可对账）被证伪。

## 7. 本轮最大风险

**一句话**：WATT 把安全折算为焦耳影子价格 `μ` 并让中间件独占仲裁权，但一旦账本失准、热模型失配或中间件被篡改，`μ` 会被系统性低估，系统将**高效而静默地饿死最关键的证书**——它不是崩溃，而是「省电地把安全边界一点点让出去」，即**优化器本身成为安全边界的最优破坏者**。
