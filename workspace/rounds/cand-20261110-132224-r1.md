# 第 44 轮（新循环第 4 轮） · Interact-to-Certify × Certify-to-Finetune：把「交互设计」与「微调」纳入可验证协同适应闭环（四层架构 v9）

> 承接第 43 轮 v20（Persona-Cert × Concurrent-Cert）。v20 自陈最大风险是「共形只保边际覆盖 + 多用户契约求交为空」。但它仍把两个环节当作**外生给定**：**(H1) 交互被当成被动观测**——系统只是"读取"人的意图，交互的**设计**（问什么、何时问、如何解释、等多久、给什么反馈）被当作 UI 细节，而非可优化的控制量；**(H2) 微调被当成离线训练**——模型/阈值更新被假定发生在部署之前，部署后的个性化适配被视为"不改变证书"的工程操作。本轮灵感词「交互设计」「微调」精确命中：**交互设计**迫使我们承认机器人可以通过**主动改变交互协议**来主动降低意图不确定性，从而合法扩张证书；**微调**迫使我们承认部署后的参数/阈值更新会**移动证书本身**，必须作为持证变换而非黑箱操作。二者耦合出本轮真正的新问题：**主动交互改变数据分布，而微调又消费这些数据——主动性与可交换性相互破坏，形成可能漂移的协同适应闭环。**

## 0. 直觉与动机

**灵感 1（交互设计 → 交互不是"读取"，而是"可持证的主动传感"）**：直觉上，当机器人不确定老人想去厨房还是卫生间时，与其保守地停在原地（可用性崩塌），不如**问一句**。但"问"不是免费的：它要求机器人停下、面向人、并在一段时间内保持安全。于是交互设计成为一个**受证书约束的控制输入**：交互动作 u∈U_I（询问/确认/解释/等待/示范/交接）本身必须满足**交互不变量**——在整个动作持续期内，对所有可能的意图，系统都不能离开安全集。在这个约束下，选择信息增益/代价最大的交互，就能**主动收缩**共形意图集 Ĥ_u^α，从而扩张交互不变集 I_u^α。一句话：**被动共形是"猜"，主动交互是"问"，而"问"必须自己先持证。**

**灵感 2（微调 → 微调不是"训练"，而是"证书的位移"）**：直觉上，用用户交互日志微调一个对话/风格适配器，似乎"只是让语气更像用户"，与安全无关。但微调会改变 m_θ(x)，而证书守卫依赖 m_θ(x) ≥ θ_guard。因此微调在数学上是**证书在持证域上的一次位移**。我们把"参数微调"和"阈值微调"统一成同一个算子 T_δ，用**证书敏感度** L_C 给出位移的 sound 上界：|m_{θ+δ}−m_θ| ≤ L_C‖δ‖。若位移只会让证书更保守（收缩），则免费准入；若想让证书更激进（扩张），则必须重验证 + 影子证书 + 信任预算。一句话：**收缩免费，扩张持证——与第 43 轮的个性化完全同构，只是从"动作空间"搬到了"参数空间"。**

**灵感 3（耦合 → 主动交互破坏共形的可交换性，微调又把它放大）**：这是本轮最锋利、也最危险的一点。共形预测的保证依赖校准集与部署点**可交换**。但主动交互设计恰恰是**按策略选样**：机器人专挑信息量大的情境去问，采到的数据就不再是目标分布的无偏样本。于是"用主动交互采的数据做微调，却用旧分布做校准"会**系统性高估覆盖**。更糟的是，微调后的策略又改变下一轮交互选择，形成正反馈。因此协同适应闭环需要一个**证书 Lyapunov 势函数**：交互、微调、校准三者共同受一个非增势约束，才能证明闭环不漂移。一句话：**主动性是杠杆，也是混杂源；微调是收益，也是漂移放大器。**

**耦合升级**：DAC（对话式主动认证器）把交互设计编译为受证书约束的主动信息获取；CFK（持证微调内核）把参数/阈值更新编译为带敏感度界的证书位移与事务；CALV（协同适应闭环验证器）在仿真中搜索漂移、混杂与投毒，把反例回灌 CKB 与 SCV。四层架构由 v8 的「仿真-检索-边缘飞轮 + 人格契约层 + 并发证书层」升级为 v9 的「仿真-检索-边缘飞轮 + 人格契约层 + 并发证书层 + **协同适应层（主动交互 / 持证微调 / 闭环无漂移）**」。

## 1. 形式化定义（增量：定义 44–50）

**定义 44（交互设计作为受证书约束的控制输入）**：交互策略 π_I:(z_t,C_t,τ_u)↦u_t∈U_I，U_I={询问,确认,解释,等待,示范,交接}。每个 u 有代价 c_I(u)、时长 d_I(u) 与信息产出。**交互不变量**：u 可执行，当且仅当存在安全集 S_safe，使得 ∀h∈Ĥ_u^α、∀t'∈[t,t+d_I(u)]，执行 u 后的状态 z_{t'}∈S_safe∩Pre_{d_I}(I_u^α)。即**交互动作自身必须持证**。这把交互从对话层软约束提升为与几何/安全同级的硬约束。

**定义 45（主动共形与策略条件覆盖）**：标准共形要求校准集与测试点可交换。主动交互按 π_I 选样，破坏可交换性。定义**交互上下文** c=(π_I,persona,交互历史)，在 c 分层下做 Mondrian 共形，要求 **策略条件覆盖** P(h∈Ĥ_u^α(c)|c) ≥ 1−α。信息增益 IG(u)=H(Ĥ_u^α(c))−E_{o∼p(·|u)}[H(Ĥ_u^α(c⊕o))]。**主动认证**：u*=argmax_{u∈U_I^safe} IG(u)/c_I(u)。**命题（主动性的覆盖代价）**：若部署策略与校准策略不一致，覆盖误差 ≤ 2·TV(D_{π_I^cal}‖D_{π_I^deploy})。故 π_I 必须写入校准证书，不能只校准模型。

**定义 46（微调算子与证书敏感度）**：微调 T_δ:θ↦θ+δ，δ 可作用于模型参数或证书阈值向量（**两尺度统一**：参数微调改变 m_θ，阈值微调改变 θ_guard，均可归约为证书位移）。在持证域 D_cert 上定义证书敏感度 L_C(θ,D_cert)=sup_{x∈D_cert}‖∇_θ m_θ(x)‖。**一阶 sound 界**：|m_{θ+δ}(x)−m_θ(x)| ≤ L_C·‖δ‖+O(‖δ‖²)。L_C 可由谱范数、Jacobian 界或区间传播（IBP）给出 sound 上界，而非采样估计。

**定义 47（持证微调 CPFT）**：δ 准入 iff：
(1) **写集隔离**：δ 的作用块与安全关键参数块不相交（安全监控/几何证书头冻结）；或
(2) **重验证**：∀x∈I_u^α，由一阶界推出 m_{θ+δ}(x) ≥ θ_guard 的 **sound 下界**；
(3) **校准有效性**：微调后校准集与部署策略仍可交换，或触发重校准。
两轨道：**收缩微调**（新证书 ⊆ 旧证书，免费）与**扩张微调**（新证书 ⊄ 旧证书，需重验证+影子证书+信任预算）。**定理**：若 δ 走收缩轨道，或同时通过 (1)+(2)+(3)，则 I_u^α 在微调前后保持，输出策略证书 sound。

**定义 48（协同适应闭环与证书 Lyapunov 函数）**：闭环 π_I→D→θ'=T_δ(θ)→π_robot(θ')→π_I。势函数
Φ = w_1(1−cov) + w_2·Gap(conservatism) + w_3(1−τ_trust) + w_4·Confound(D,π_I)，
其中 cov 为策略条件覆盖，Gap 为「证书可行域−实际可达域」的保守性间隙，Confound 为混杂间隙。**协同适应定理（无漂移）**：若每步 (i) 交互满足定义 44 的交互不变量，(ii) 微调走定义 47 的 CPFT 准入，(iii) Φ 非增，则任意可达状态证书 sound 且 Φ 收敛；反之，任一无闸门的主动交互或微调都可能使 Φ 增大并最终破坏覆盖或安全。

**定义 49（交互混杂与校准证书）**：主动交互使数据分布依赖策略：D=D(π_I)。定义混杂间隙 γ(π_I)=TV(D(π_I)‖D_target)。**命题**：离线微调+离线校准的覆盖高估 ≤ γ；即「用主动交互采的数据微调，却用旧分布校准」会系统性高估覆盖。因此校准必须 **on-policy**（同一 π_I 的留出数据）或做倾向加权（propensity weighting）。这把第 43 轮的「边际 vs 条件覆盖」升级为「**策略条件覆盖**」。

**定义 50（微调事务与回滚证书）**：每次准入微调是一个事务：记录 (δ,D,optimizer state,证书 delta,父版本哈希)，原子提交并写审计日志；检测到覆盖失效/安全违例时在 t_rollback 内原子回滚。与第 43 轮租约/epoch 结合：微调提交递增 certificate epoch，监控器快照读据此拒绝撕裂状态。**命题**：事务化+回滚证书 ⇒ 微调不可产生「半更新」的不可审计状态。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-60 DIALOGICAL-ACTIVE-CERTIFIER（对话式主动认证器 DAC）
1. **交互动作空间与不变量检查器**：编译 U_I、代价/时长，逐步检查交互不变量（定义 44）；不安全的"问"直接不可执行。
2. **主动信息获取**：在交互预算内最大化 IG/代价，必要时组合多步交互（询问→示范→确认）。
3. **策略条件共形**：按交互上下文 Mondrian 分层 + 倾向加权，保证定义 45 的策略条件覆盖。
4. **预算与回退**：交互预算耗尽或覆盖失效 → 退回被动共形 + 纯收缩个性化（第 43 轮底线）。

### 2.2 IP-61 CERTIFIED-FINETUNE-KERNEL（持证微调内核 CFK）
1. **证书敏感度估计**：谱范数/Jacobian/IBP 给出 L_C 的 sound 上界，避免用采样冒充证明。
2. **适配器隔离**：冻结安全监控/几何证书关键块，仅微调语义/对话/风格 LoRA；写集由工具生成而非手写。
3. **双轨准入**：收缩轨道免费；扩张轨道重验证 + 影子证书 + 信任预算扣减。
4. **微调事务**：原子提交、epoch 递增、审计日志、回滚证书（定义 50）。

### 2.3 IP-62 CO-ADAPTATION-LOOP-VALIDATOR（协同适应闭环验证器 CALV）
1. **闭环仿真**：交互→数据→微调→行为→再交互，搜索漂移、发散、覆盖崩塌。
2. **混杂审计**：估计 γ(π_I)、检验可交换性、检出"主动选样导致的高估覆盖"。
3. **Lyapunov 势监控**：在线估计 Φ，检测非增性被破坏的早期信号。
4. **对抗交互与投毒**：对话注入、诱导性确认、交互日志投毒、伪反馈。

## 5. 本轮最大风险

**一句话**：主动交互设计本身**按策略选样**，会破坏共形预测赖以成立的可交换性——「用主动问出来的数据做微调、却用旧分布做校准」会系统性高估覆盖，而微调又反过来改变下一轮交互策略，形成可能把安全证书悄悄拖出有效域的**协同适应漂移**；因此 E96（策略条件覆盖/混杂审计）与 E99（Φ 非增/无漂移）必须设为红线，默认回退到「被动共形 + 无在线微调 + 纯收缩个性化」。

# 第 44 轮产物 · 创新点清单 v21：Interact-to-Certify × Certify-to-Finetune（DAC × CFK × CALV）× 可验证协同适应闭环（四层架构 v9）

## 2. 关键算法（伪代码）

### IP-60 DAC：交互不变量、主动认证与策略条件共形
```
def interaction_invariant_ok(z, u, H_alpha, C_global, d):
    # 交互动作自身必须持证：持续期内对所有可能意图都安全
    if conflicts(u, C_global): return False
    return all(safe(z, u, h, C_global) for h in H_alpha) \
           and z in pre_d(H_alpha) and z in S_safe

def choose_interaction(z, H_alpha, U_I, budget, C_global):
    cand = [u for u in U_I
            if interaction_invariant_ok(z, u, H_alpha, C_global, dur(u))]
    scored = [(u, info_gain(u, H_alpha) / cost(u))
              for u in cand if cost(u) <= budget]
    if not scored:
        return PASSIVE                      # 无安全交互 => 退回被动共形
    return max(scored, key=lambda x: x[1])[0]

def policy_conditional_conformal(hist, alpha, context, propensities):
    scores = calibration_scores[context]     # Mondrian by interaction context
    w = importance_weights(propensities)     # 倾向加权，纠正主动选样偏差
    q = weighted_quantile(scores, 1 - alpha, w)
    return IntentSet(center=predict_intent(hist), radius=q, context=context)
```

### IP-61 CFK：证书敏感度、双轨准入与微调事务
```
def cert_sensitivity(theta, D_cert):
    # sound 上界：谱范数 / Jacobian 界 / 区间传播，禁止用采样冒充证明
    return sup_jacobian_norm(m, theta, D_cert)        # L_C

def certified_finetune(theta, delta, I_u, theta_guard, mode, tau_u):
    if writes_safety_critical(delta):                 # 写集隔离（定义 47.1）
        return REJECT
    L_C = cert_sensitivity(theta, I_u)
    worst = min_margin(theta, I_u) - L_C * norm(delta)  # sound 下界
    if worst >= theta_guard:
        return ADMIT_CONTRACTION(theta + delta)       # 新证书 ⊆ 旧证书，免费
    if (mode == EXPANSION and reverify(theta + delta, I_u)
            and shadow_cert.zero_violation() and tau_u > 0):
        cost = displacement(delta) * kappa_trust
        return ADMIT_EXPANSION(theta + delta, cost)   # 扩张持证，扣信任预算
    return REJECT

def finetune_transaction(theta, data, delta, mode):
    parent = version_hash(theta)
    theta2 = certified_finetune(theta, delta, I_u, theta_guard, mode, tau_u)
    if theta2 is REJECT:
        return theta
    epoch = bump_cert_epoch()                         # 原子提交，配 CCR 快照读
    log_audit(parent, version_hash(theta2), delta, data, epoch)
    return theta2

def rollback(theta2, parent, deadline):
    # 覆盖失效/安全违例 => 在 deadline 内原子回滚，绝不半更新
    return restore(parent) if violation_detected() and within(deadline) else HALT
```

### IP-62 CALV：闭环势函数与漂移闸门
```
def coadapt_step(z, H_alpha, theta, pi_I, tau_u):
    u  = choose_interaction(z, H_alpha, U_I, budget=tau_u, C_global=C_global)
    D  = collect(z, u, pi_I)                          # 主动采样的数据
    H2 = policy_conditional_conformal(D, alpha, context=u, propensities=pi_I)
    I2 = robust_invariant(C_global, H2)
    delta = train_adapter(D, theta)
    theta2 = finetune_transaction(theta, D, delta, mode=choose_mode(D))
    phi_now  = potential(H_alpha, theta, tau_u, confound(D, pi_I))
    phi_next = potential(H2, theta2, tau_u - cost(u), confound(D, pi_I))
    # 非增闸门：漂移即拒绝本次交互/微调，保留旧策略
    return (theta2, H2) if phi_next <= phi_now else (theta, H_alpha)

def audit_exchangeability(D, pi_I, D_target):
    # 主动选样是否破坏可交换性；返回混杂间隙上界 gamma
    return tv_distance(weighted(D, pi_I), D_target)
```

### IP-51/53/58 升级：交互与微调感知的守卫
```
def car_transition_guard(e, x, cert_obj, persona, lease, t, ft_epoch, u_int):
    theta = cert_obj.alpha_e[e] * cert_obj.theta_sim[e]
    m_lookup = cert_lookup_L0(x).m_lo[e]
    m_lease  = lease.m - lease.lam * (t - lease.tau)
    m_cap    = persona_cap[e](persona)                # 只做上限收缩
    ft_ok    = (cert_obj.epoch == ft_epoch)           # 拒绝撕裂/陈旧版本
    int_ok   = interaction_invariant_ok(x, u_int, H_alpha, cert_obj.C, dur(u_int))
    return ft_ok and int_ok and min(m_lookup, m_lease, m_cap) >= theta \
           and lease_valid(lease, theta, t)
```

## 5. 风险与缓解（增量）

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 主动交互按策略选样，破坏共形可交换性，覆盖被系统性高估 | 高 | E96 红线；策略条件共形 + 倾向加权；on-policy 留出；γ 写入校准证书 |
| 微调改变证书而未被察觉，安全边际被静默侵蚀 | 高 | E97 红线；L_C sound 上界；适配器隔离；扩张重验证 + 影子证书 |
| 交互→数据→微调→行为正反馈导致闭环漂移/发散 | 高 | E99 红线；Φ 非增闸门；漂移即拒绝本次更新并回滚 |
| 交互动作本身不安全（如长时间停顿在动态场景） | 中-高 | 定义 44 交互不变量；不安全交互不可执行；HI 模式只保留急停交互 |
| L_C 界过松导致收缩轨道几乎不可用（可用性崩塌） | 中 | 分块敏感度；LoRA 低秩约束；按关键级分别定界；实测界/理论界监控 |
| 交互日志投毒/伪反馈污染微调 | 中-高 | E101 红线；日志签名与来源追溯；异常反馈隔离；投毒数据禁入训练 |
| 微调事务与并发监控交错导致撕裂/半更新 | 中 | E100 红线；epoch 递增 + seqlock 快照读；回滚证书；审计线性一致性 |

## 6. 本轮最大风险

**一句话**：主动交互设计本身**按策略选样**，会破坏共形预测赖以成立的可交换性——「用主动问出来的数据做微调、却用旧分布做校准」会系统性高估覆盖，而微调又反过来改变下一轮交互策略，形成可能把安全证书悄悄拖出有效域的**协同适应漂移**；因此 E96（策略条件覆盖/混杂审计）与 E99（Φ 非增/无漂移）必须设为红线，默认回退到「被动共形 + 无在线微调 + 纯收缩个性化」。
