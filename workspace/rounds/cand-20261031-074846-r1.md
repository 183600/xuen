# 第 13 轮 · JOLT：关节空间短 chunk + 力矩可行性筛选 + anytime 执行

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是累计第 13 轮（用户称新循环第 1 轮），三个灵感词是「低延迟推理」「力矩控制」「关节空间控制」。本轮不推倒第 12 轮 CHUNK-SERVO，而是把它从 EE 空间推进到关节空间，把 30 步开环推进到 6–8 步 anytime 执行，把「没有力矩通道」重定义为「逆动力学力矩可行性」。

## 0. 先给结论：真正的杠杆不是更大的 VLA，而是动作空间和执行契约

截至 2026-10-31，榜单仍是 8 个模型、榜首 MolmoAct2 29.7%。但 `leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，8 个模型 ×32 任务的 `step ~ success` 回归 **R² > 0.999999**，256 个任务成功率里有 **232 个不是 10% 的整数倍**；`runs.html` 写着 256/256，实际只渲染 8 行并显示「即将发布」。所以 29.7% 只能当预览上限，不能当 SOTA、不能当难度表。

真正共享的瓶颈有三个，而且都不是「语义不够强」：

1. **动作空间错配**：官方 WLA、π0.5、GR00T 等基线输出 EE 相对位姿；但挑战赛数据里原生动作是 **7-DoF 关节绝对目标**。把关节演示转成 EE 再转回关节，会引入 IK、工具坐标、相机外参和奇异点误差；而 API 本来就支持 `control_space="joint"`。
2. **执行契约错配**：30 步 chunk @30Hz = **1 秒开环**；接触、插入、挂杯、拉拉链、拧瓶盖都发生在最后 3 厘米、最后 0.3 秒。chunk 内没有新观测，也没有打断机制。
3. **物理反馈错配**：API 没有力矩/力/触觉，只有位置目标；但关节空间动作可以用 G1 URDF 做**逆动力学力矩检查**。G1 腕部 `wrist_pitch/wrist_yaw` 的力矩上限只有 **5 N·m**，而肩/肘/腕 roll 是 25 N·m——腕部是最容易被位置策略打饱和的地方。

所以本轮的押注是 **JOLT**：

> **J**oint-space（关节空间直控） + **O**nline/anytime（流式短 chunk） + **L**ow-latency（把推理藏进执行） + **T**orque-aware（用逆动力学力矩做可行性筛选，而不是发力矩指令）。

一句话：**把「预测 1 秒的 EE 轨迹」改成「预测 200 毫秒的关节目标，并用 G1 的逆动力学力矩筛掉不可行的候选」；不发力矩，但让位置目标力矩可行、接触可感。**

三个可验证创新点：

1. **Joint-native action head**：把 WLA 的 54D EE 动作头改成 23D 关节动作头（左右臂 7+7、夹爪 1+1、pivot 7），用挑战赛原生 `action.left_arm/right_arm` 微调；验证关节空间是否在接触任务上优于 EE（E1）。
2. **Torque-feasibility selection**：对 action head 采样的 N 个关节 chunk 做 RNEA 力矩评分 + 腕部力矩裕度 + jerk 惩罚，选最优；再用线性化 QP 把选中 chunk 投影到关节/速度/力矩约束内（E3）。
3. **Anytime short-chunk execution**：`action_chunk_size=6–8`，VLM 特征缓存、action head 高频、下一 chunk 未就绪时用 coast chunk 兜底；用跟踪误差触发位置基柔顺，用腕部相机内参做最后 3 厘米 IBVS（E2/E4/E5）。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **关节空间控制** | 原生 7-DoF 关节绝对目标；直接对接 `control_space="joint"`；RNEA/Jacobian 用 URDF | 不做 EE→IK→关节的二次转换；不猜 `pivot` 的 waist 语义 |
| **力矩控制** | 逆动力学力矩作为 best-of-N 评分、QP 约束、腕部 5 N·m 裕度、跟踪误差柔顺 | 不发 `tau`（API 没有）；不假设已知物体质量；不把力矩当硬安全保证 |
| **低延迟推理** | 6–8 步短 chunk；VLM 特征缓存；action head 流式；coast/blend；p99 延迟预算 | 不做 30Hz 广域网全模型推理；不做第二个学习模型；不把 30 步 chunk 当默认 |

## 1. 本轮新核实的事实（只列会改变方案的）

### 1.1 数据里有原生关节动作，不只是 EE

HangCup 的完整 `meta/info.json`（2026-10-31 重新抓取）明确列出：

- `action.left_arm` / `action.right_arm`：`[7]`，float32，名字是 `shoulder_pitch, shoulder_roll, shoulder_yaw, elbow, wrist_yaw, wrist_roll, wrist_pitch`。
- `action.left_gripper` / `action.right_gripper`：`[1]`，`gripper_pos`。
- `action.pivot`：`[7]`，名字是 `vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height`。
- `action.lower_body`：`[15]`；`action.left_ee_pose_gripper_base` / `right_ee_pose_gripper_base`：`[6]`。
- 抽样行里 `action.left_arm` 与 `observation.state.left_arm` 只差约 0.01–0.04 rad，说明 **action 是下一帧的绝对关节目标**，不是 delta。
- HangCup：1043 episodes / 194,564 frames / 30fps；官网称 32 任务、32000 episodes、169h。第 12 轮统计的 33,276 episodes / 169.28h 与官网 32000/169h 略有差异，以官网和逐数据集 `info.json` 为准。

**含义**：关节空间不是「额外加的控制器」，而是数据原生表示。用关节动作微调 action head，比把关节演示转成 EE 再学一遍更直接。

### 1.2 腕部相机其实有内参（修正第 12 轮）

第 12 轮写「腕部相机没有内参」，本轮复核完整 `meta/info.json` 的 `camera_params` 后发现这是错的：

- `wrist_left.color.camera_matrix`：`fx=436.4058, fy=435.9215, cx=323.9217, cy=242.9332`，畸变模型 `distortion.inverse_brown_conrady`。
- `wrist_right.color.camera_matrix`：`fx=435.1151, fy=434.4995, cx=319.0249, cy=240.9933`。
- 头双目：`fx≈282.37`，基线 **58.2526 mm**，`rectified: true`。
- `camera_params` 里没有腕部相机到 EE 的外参；URDF 只有 `d435_joint`（头相机），没有腕部相机 frame。

**含义**：腕部 IBVS 可以直接做，但必须先补一次手眼标定（或在线估计图像雅可比）。第 12 轮的「腕部无内参」风险应降级为「腕部无外参」。

### 1.3 `pivot` 是 episode 常数、任务相关；不是 waist 关节

对 HangCup、PlugInEthernet、OrganizeBookshelf、ConveyorSorting、ToolboxStorage 抽样：

- `action.pivot = [0, 0, 0, 0, 0.15, 0, 0.74]`，整段不变。
- FoldTowel 的 `action.pivot = [0, 0, 0, 0, 0, 0, 0.74]`，第 5 维是 0，不是 0.15。
- `action.base_command = [0, 0, 0, 0.74]`；`action.waist_action_joint` 逐帧变化，但**不等于** `pivot[3:6]`。

**含义**：`pivot` 更像「下身体/腰部的任务级姿态命令」，不是逐帧 waist 关节目标。最稳的做法是先按任务输出数据集里的常数 `pivot`，只学双臂+夹爪；若单任务通道证明需要 waist 运动，再把 `pivot` 作为低方差 7D 头学习。不要猜 `pivot_3..5` 的符号。

### 1.4 关节顺序和 URDF 不一致

- 数据集顺序：`shoulder_pitch, shoulder_roll, shoulder_yaw, elbow, wrist_yaw, wrist_roll, wrist_pitch`。
- G1 URDF（`g1_29dof_with_hand_rev_1_0.urdf`）顺序：`shoulder_pitch, shoulder_roll, shoulder_yaw, elbow, wrist_roll, wrist_pitch, wrist_yaw`。
- 转换：`q_urdf = q_ds[[0,1,2,3,5,6,4]]`；`q_ds = q_urdf[[0,1,2,3,6,4,5]]`。

**含义**：RNEA、Jacobian、关节限幅、力矩裕度必须先做这个置换。否则力矩最大的关节会被算到错误的轴上，腕部 5 N·m 约束会完全失效。

### 1.5 G1 腕部力矩上限只有 5 N·m

URDF 的 `limit`：

- 肩 pitch/roll/yaw、肘、腕 roll：`effort=25 N·m`，`velocity=37 rad/s`。
- 腕 pitch、腕 yaw：`effort=5 N·m`，`velocity=22 rad/s`。
- 腰 yaw：88 N·m；腰 roll/pitch：35 N·m。

**含义**：`Unlock`、`PourOutMedicine`、`ZipUp`、`PlugInEthernet` 这类需要腕部旋转/对准的任务，位置策略很容易让腕部力矩饱和；关节空间 + 力矩筛选在这里不是装饰，而是直接对应硬件约束。

### 1.6 WLA 基座是 EE 空间；改关节空间是 action-head 微调

- UnifoLM-WLA-1.0：6B，约 2500h 真机，64 任务；默认 `chunk_size=30`、30fps、4 步去噪；冻结 VLM，只训 DiT action head + robot-state projector，单张 24GB 可微调。
- 54D 统一动作是 EE 相对 xyz+rotvec、gripper、waist、base、legs；`_ACTIVE_SLOT_SPECS` 里没有 arm joint 槽位。
- 但挑战赛数据集有 `action.left_arm/right_arm`。可以新增关节槽位、把输出投影改成 23D（7+7+1+1+7），从 base checkpoint 初始化，VLM 继续冻结。

**含义**：关节空间路线是 **同一个模型的 action-head 微调**，不是第二个模型；单模型合规风险可控。

### 1.7 榜单仍是预览；不要用任务排名当难度表

- `leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`；`step ~ success` 的 R² > 0.999999，最大残差 <0.006。
- 256 个成功率里 232 个不是 10% 的整数倍（如 27.29%、27.85%、37.01%），而每任务只有 10 次 trial。
- `runs.html` 写 256/256，实际只渲染 8 行并显示「即将发布」。
- 头部：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。

**含义**：榜单只能当「预览上限」；任务优先级应该从**接触密度 × 腕部力矩需求 × 当前成功率缺口**推，而不是从榜单任务排名推。

### 1.8 相关近期工作：三个点都出现了，但没人把它们合在 UniBot 约束下

- **TANGO**（CoRL 2026）：29-DoF 关节空间人形 VLA，用于杂乱环境导航；real-time chunking + 低层 tracker。证明关节空间人形 VLA 可行，但不是桌面接触操作。
- **TA-VLA**（CoRL 2025）：torque-aware VLA，torque adapter + 辅助力矩预测；需要力矩传感。挑战赛没有力矩观测，不能直接照搬。
- **ActionGround**（arXiv 2609.33256）：training-free 的 Euler-Lagrange runtime layer，7-DoF Franka，+6pp success、+19.3pp stability；它用动力学项做控制修正，不是关节 chunk 的 best-of-N/QP，也不是 G1 腕部力矩约束。
- **VLA-Corrector**（arXiv 2607.01804）：latent vision monitor + 截断 + OGG 重规划，自适应 horizon；它解决视觉漂移，不解决关节力矩可行性。
- **PACT-VLA**（arXiv 2610.28019）：用 pre-commit observation 做 chunk 候选选择；它用 VLA 自身打分，我们用的是物理力矩/ jerk 打分，可互补。
- **D²-VLA**（arXiv 2609.34792）：双频 VLM/action，KV-cache 接口；证明「慢 VLM + 快 action」是活跃方向。
- **FlashVLA**（arXiv 2608.27384）：streaming action decoding，多噪声级 chunk 缓冲；可作为 anytime 的 chunk ladder。
- **HumanoidVLM**（arXiv 2601.14874）：G1 上的 Cartesian impedance → IK → 位置控制器；它走 EE/IK，我们走关节直控。
- **GROOVE**（arXiv 2609.13695）：QP 降 jerk；我们的 QP 同时加力矩约束。

**Gap**：UniBot 同时具备「原生关节动作 + 无力矩传感 + 固定 chunk + 远程 API」四个约束；现有工作没有把 **关节空间人形桌面操作 + 逆动力学力矩可行性 + anytime 短 chunk** 合起来。JOLT 就押这个组合。

## 2. 诊断：三个错配

### 2.1 动作空间错配：EE 是「借来的表示」

EE 基线的链路是：关节演示 → 正运动学 → EE 相对位姿 → 训练 → 推理 → IK → 关节目标。每一跳都可能引入误差：

- 工具坐标/TCP 偏移（夹爪长度、Dex1 指尖）不一致；
- IK 在肩/肘奇异点附近解不稳定；
- 腕部 5 N·m 力矩约束在 EE 空间不可见；
- 相机外参误差会直接变成 EE 目标误差。

关节空间把链路缩短为：关节演示 → 训练 → 关节目标。没有 IK，没有 TCP 转换，力矩检查也在同一空间。代价是模型要学 7-DoF 冗余臂的关节轨迹，但 33k 演示足够。

### 2.2 执行契约错配：1 秒开环 vs 最后 0.3 秒接触

`action_chunk_size=30` @30Hz 意味着一次 `get_action` 后 1 秒内不看新图。接触事件发生在 chunk 内部时，模型只能等下一个 chunk。把 H 降到 6–8：

- H=6 → 200ms；H=8 → 267ms；
- 接触段可以每 200ms 修正一次；
- 但推理必须跟得上：如果 action head + VLM 需要 300ms，H=6 会每块停 100ms。**低延迟推理不是「模型更快」，而是「把推理藏进执行」**：VLM 特征缓存、action head 高频、下一 chunk 预计算。

### 2.3 物理反馈错配：没有力矩，但有力矩模型

API 不提供 `tau`，也不接受 `tau`。但 G1 URDF 是公开的，数据集有逐帧 `q`、`qdot`（可由差分得到）、`qddot`。于是可以算：

```text
tau = M(q) qdd + C(q, qd) qd + g(q) + J^T f_ext
```

`f_ext` 未知（物体质量、接触力），所以力矩只能当**相对可行性分数**，不能当硬安全保证。即便如此，它能抓住三类失败：

1. 腕部 5 N·m 饱和（Unlock/PourOutMedicine/ZipUp）；
2. 高 jerk/高加速度导致的跟踪滞后（插入/挂杯）；
3. 候选 chunk 之间的动力学不一致（chunk 边界抖动）。

## 3. 方法：JOLT

### 3.1 总架构

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / joint chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)       │
                    │  ├─ joint action adapter (23D)      │
                    │  ├─ anytime scheduler + coast       │
                    │  ├─ torque verifier (RNEA/QP)       │
                    │  ├─ compliance (tracking error)     │
                    │  └─ wrist IBVS (optional)           │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared GPU server                  │
                    │  WLA VLM (cached) + joint DiT head  │
                    └─────────────────────────────────────┘
```

- 唯一学习模型：WLA VLM + joint action head（同一个 checkpoint）。
- 力矩 verifier、QP、compliance、IBVS 都是确定性控制器，无学习权重。
- 每个端口独立 `reset()`、独立 action queue、独立 compliance 状态；GPU server 只共享权重，按 session ID 隔离。
- GPU server 可把 N 个端口的 action-head 请求做 batch，提高并发；VLM 特征按端口缓存。

### 3.2 关节空间 action head

动作向量（23D）：

```text
a = [left_arm(7), right_arm(7), left_gripper(1), right_gripper(1), pivot(7)]
```

- 左右臂：绝对关节目标（rad），与数据集 `action.left_arm/right_arm` 同序；进模型前按数据集均值/方差归一化，出模型后反归一化并 clip 到 URDF 限位。
- 夹爪：数据集 `action.left_gripper/right_gripper` 约 4.5；先按数据集范围归一化，再在 `example_env.py`/单任务通道确认 API 的 0–1 或 0–5 方向。
- `pivot`：先用任务级常数（大多数任务 `[0,0,0,0,0.15,0,0.74]`，FoldTowel `[0,0,0,0,0,0,0.74]`）；若后续证明需要，再换成 7D 低方差头。
- chunk：H=6–8；训练时用同样的 H，避免训练/推理 horizon 不一致。
- 损失：关节位置 L1/L2 + 速度平滑 + 夹爪 MSE；可选辅助力矩回归（用 RNEA 离线算标签），只作为表示学习正则，不在推理时发力矩。

**为什么不用 16D + 常数 pivot？** 因为 `pivot` 是任务相关的（FoldTowel 的第 5 维不同），但它在 episode 内不变。用 23D 头让模型自己学，成本很低；如果数据证明 7D 头学不动，再退回 16D + 任务常数。

### 3.3 力矩可行性筛选

对 action head 采样 N 个候选 chunk（不同噪声种子），对每个候选：

1. **补全轨迹**：用当前 `q, qdot` 和候选 `q_{1:H}` 做有限差分，得到 `qdot, qddot`；首帧用当前速度做边界条件。
2. **RNEA**：用 G1 URDF（先做 1.4 的关节置换）算 `tau_{1:H}`；物体负载按 `m_p ∈ {0,1,2} kg` 三个假设各算一次，取最差/95 分位。
3. **评分**：

```text
J_tau   = sum_k ||tau_k / tau_max||^2
J_jerk  = sum_k ||q_{k+1} - 2q_k + q_{k-1}||^2
J_track = ||q_{1:H} - q_ref||^2
J_wrist = sum_k max(0, 0.3 - margin_k)^2
margin_k = min_i (1 - |tau_{k,i}| / tau_max_i)   # 只看 wrist_pitch/yaw
J = J_tau + alpha J_track + beta J_jerk + gamma J_wrist
```

4. **选最优**：`n* = argmin_n J^(n)`；如果 N=1，就只做 QP 投影。
5. **QP 投影**（可选）：在 `q_ref` 附近线性化 RNEA，解

```text
min_dq  ||dq||^2 + lambda ||D dq||^2 + mu ||D^2 dq||^2
s.t.    q_min <= q_ref + dq <= q_max
        |qdot_ref + D dq / dt| <= qdot_max
        |tau(q_ref) + J_tau(q_ref) dq| <= 0.7 tau_max
```

用 2–3 次 SQP 迭代；`J_tau = ∂tau/∂q` 可用 Pinocchio 的 torque regressor 或有限差分。QP 不改变 chunk 的语义，只把不可行的候选拉回可行域。

**关键诚实声明**：这不是力矩控制。API 不接受力矩，低层控制器也不暴露力矩反馈；我们只是用逆动力学模型给位置目标做**可行性先验**。物体质量未知时，力矩分数只用于候选之间的相对排序，不能当绝对安全证书。

### 3.4 Anytime 执行：把推理藏进执行

设控制频率 `f_c`（先按数据集 30Hz 假设，单任务通道实测），chunk 时长 `T_exec = H/f_c`，推理时间 `T_inf`。连续执行条件：

```text
H >= f_c * T_inf
```

如果 `T_inf=150ms`，30Hz 下 H>=5；取 H=6–8 留 25–40% 余量。调度：

```text
get_action(obs):
    if next_chunk is ready:
        chunk = next_chunk
    else:
        chunk = coast(obs)          # q_t + k*dt*qdot_t, clip
    launch_async(compute_next_chunk(obs))
    return adapter.to_api(chunk)
```

- **VLM 特征缓存**：VLM 每 K 个 chunk 刷新一次（K=4–8），action head 每个 chunk 都跑；腕部图只用于 IBVS，不一定要每块进 VLM。
- **coast chunk**：用低通后的 `qdot_t` 外推，clip 到关节限位/速度限位；新 chunk 到达后前 2–3 步做线性 blend，避免速度跳变。
- **chunk ladder**（可选）：借用 FlashVLA 的多噪声级思路，先出一个粗 chunk 保底，再出一个细 chunk 替换；任何时刻都有合法动作。
- **chunk size 扫描**：H ∈ {4,6,8,12,30}；选满足 p99 推理预算的最小 H。H 不是拍脑袋常数，是提交前要扫的控制参数。

### 3.5 位置基柔顺：用跟踪误差当「接触传感器」

没有力传感器，但有关节指令和关节测量。定义：

```text
e_q = q_cmd - q_meas
if ||e_q|| > eps for K consecutive frames:
    # 接触/饱和/被挡住
    alpha = clip((||e_q|| - eps) / delta, 0, alpha_max)
    q_cmd' = (1 - alpha) q_policy + alpha q_meas
    shorten chunk to 2-3 steps; request replan
else if ||e_q|| < eps/2:
    alpha -> 0; restore normal tracking
```

- 这是**位置基阻抗**：不发力矩，只把目标往测量位置拉，降低有效刚度。
- 触发后不要立刻大撤退；先保持 2–3 帧，确认不是单帧噪声，再决定回退/重抓。
- 与第 12 轮 GEO-RESIDUAL 的编辑检测互补：GEO 看视觉残差，JOLT 看本体跟踪残差；两者都触发才进入 RECOVER。

### 3.6 腕部 IBVS：最后 3 厘米的关节空间闭环

腕部相机有内参（1.2），所以可以做 IBVS；缺的是相机到 EE 的外参。两条路：

1. **离线手眼标定**：棋盘格 + 20 个姿态，解 `AX=XB`；重投影误差目标 ≤5px。URDF 没有腕部相机 frame，所以不能用 URDF 直接拿。
2. **在线图像雅可比**：不标外参，直接用 `ds = J dq` 的 Broyden 更新：

```text
J_{t+1} = J_t + ((ds_t - J_t dq_t) dq_t^T) / (||dq_t||^2 + eps)
```

只在该 chunk 的 `||dq_t||` 足够大时更新；小步时冻结。这样内参/外参误差都被 `J` 吸收。

控制律：

```text
e = s_current - s_target          # 2D/3D 特征误差
dq = -lambda (J^T J + mu I)^-1 J^T e
q_cmd = q_policy + clip(dq, ±dq_max)
```

- 目标特征 `s_target` 来自第 12 轮 DG-KEYFRAME 检索的演示腕部目标图；用 ORB/颜色/轮廓做局部匹配。
- 只在最后 3 厘米、特征置信度高时启用；置信度低就退回纯策略。
- 这是确定性控制器，不是第二个学习模型；单模型合规。

### 3.7 泛化与训练

- **数据**：32 任务、约 33k episodes、30fps；按任务平衡采样，避免长任务（ToolboxStorage 37.6s）压过短任务（HangCup 6.2s）。
- **输入**：头双目 + 左右腕部（可按需 resize）、双臂关节、夹爪、`lower_body`、语言；当前 EE 位姿可选（只作为辅助输入，不作为动作空间）。
- **增强**：物体位置抖动、背景/桌布替换、干扰物叠加、关节状态噪声、动作时间缩放；不要过度几何增强，避免破坏接触相位。
- **5 类泛化**：位置（物体/目标偏移）、干扰物（额外物体）、背景（颜色/纹理）、未见物品（同类不同外观）、人为干扰（执行中移动物体）。关节空间对前三类天然友好；未见物品靠 VLM 语义；人为干扰靠 compliance + 重规划。
- **划分**：按 session/物体/背景分组，禁止相邻帧跨 split；离线指标用 chunk MSE + DTW，不只看 MSE。

## 4. 竞赛策略：320 trials 是投资组合

### 4.1 用物理量排任务，不用预览榜单排任务

先做 E0：对 32 任务的演示轨迹算 RNEA 力矩（负载 0/1/2 kg），统计：

- 腕部 `wrist_pitch/yaw` 的力矩裕度分布；
- 肩/肘力矩峰值；
- 高 jerk 帧比例；
- 接触动词/阶段（先验）。

按 `腕部力矩需求 × 接触密度 × 当前成功率缺口 / 工程成本` 排优先级：

- **A 档（力矩/接触优先）**：Unlock、PourOutMedicine、ZipUp、PlugInEthernet、HangCup、ArrangeTestTubes、PlugCharger、StackBowls。
- **B 档（回归/变形）**：FoldTowel（pivot 第 5 维=0，变形任务，防回归）、PackBag、StorePaddle、OrganizeStationery。
- **C 档（语义/长程）**：FruitSorting、ColorArrangement、SpellRobot、ConveyorSorting；先保留 VLA 基线，不投关节/力矩工程。

这张表是 E0 之前的先验；E0 跑完后用真实力矩裕度重排。

### 4.2 单任务通道协议

1. 选 5 个代表任务：PlugInEthernet（插入）、HangCup（挂）、Unlock（腕部力矩）、ZipUp（腕部力矩+接触）、FoldTowel（变形/回归）。
2. 每个任务 5 次配对 A/B：EE 基线 vs 关节；H=30 vs H=6/8；torque off/on；compliance off/on；wrist IBVS off/on。
3. 记录成功、步骤分、耗时、p99 推理、暂停时长、跟踪误差峰值。
4. 通过标准：至少 3 个任务 +10pp；FoldTowel 不回归 >5pp；p99 推理不超过 `H/f_c` 的 80%。
5. 再扫 H ∈ {4,6,8,12} 和 N ∈ {1,2,4}；选延迟/成功率的最佳折中。

### 4.3 提交节奏

- 先交**安全基线**（官方 WLA EE、H=30、pivot 常数），锁定「更早提交」的 tie-break。
- 再交**关节空间版**（23D、H=6/8、无 torque/QP）；验证 joint vs EE。
- 再交**力矩/compliance 版**；只有 E3/E4 过门才上。
- 最后交**全量版**；不要在 320 trials 上直接试未过门的组合。

### 4.4 统计

- 320 trials 下 `p≈0.25` 的单次标准误约 `sqrt(0.25×0.75/320)=2.42pp`；配对设计会低一些，但**不要声称 +1–2pp 是结论**。
- 人为干扰轴占 20%；若恢复 +10pp，全局约 +2pp。
- 8 个接触任务各 +10pp，全局 +2.5pp；16 个各 +10pp，全局 +5pp。
- 用配对 bootstrap/置换检验；报告置信区间，不只报均值。

## 7. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 关节空间过拟合 | 位置/背景泛化变差 | 图像/关节噪声增强；按 session 划分；E6 五轴验证 |
| 物体质量未知 | 力矩分数偏差 | 0/1/2 kg 最坏情况；只用相对排序；腕部裕度优先 |
| URDF 与实际 G1 不一致 | RNEA 误差 | 用 MuJoCo/Pinocchio 校验；用跟踪误差在线校正；力矩不作硬安全保证 |
| 腕部外参缺失 | IBVS 方向错 | 一次性手眼标定；在线 Broyden 兜底；置信度低退回策略 |
| `pivot` 语义不明 | 下身体不动/错误 | 先用数据集常数；单任务通道验证；不猜符号 |
| 单模型解释 | 被判定第二个模型 | joint head 是同一 checkpoint；verifier/QP/compliance/IBVS 无学习权重；文档写清 C1/C2/C3 |
| VLM 6B 太慢 | H=6 仍暂停 | 特征缓存；量化/蒸馏；换小基座；H 扫描 |
| 评测频率未知 | chunk 时长算错 | 单任务通道测 `f_c`；按实测重选 H |
| 关节动作噪声 | 抖动/超限 | 低通/限幅/QP；chunk blend；速度约束 |
| 安全 | 碰撞/过载 | 力矩/速度/限位约束；跟踪误差即停；最大重试 |

**单模型合规的三种模式**（沿用第 12 轮）：

- C1：离线标注/检索索引，不参与在线推理；
- C2：确定性控制器（力矩 verifier、QP、compliance、IBVS），无学习权重；
- C3：同一 checkpoint 的 joint action head，不加载第二个学习策略。

提交材料必须明确：JOLT 只有一个学习模型（WLA VLM + joint DiT head）；其余都是 C2 控制器。

| `action.pivot` | `[7]` | `vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height` |
| `action.lower_body` | `[15]` | 双腿 12 + 腰 3 的绝对关节目标 |
| `action.left_ee_pose_gripper_base` / `right_ee_pose_gripper_base` | `[6]` | EE 绝对位姿 |
| `action.gripper_controls` | `[4]` | `left_trigger, left_squeeze, right_trigger, right_squeeze` |

抽样行里 `action.left_arm` 与 `observation.state.left_arm` 只差约 0.01–0.04 rad，说明 **action 是下一帧的绝对关节目标**，不是 delta。`action.left_gripper` 与 `observation.state.left_gripper` 也接近（4.5 vs 4.5068），说明夹爪动作是绝对位置目标。

#### 1.3.3 `pivot` 是 episode 常数、任务相关

对 6 个任务抽样（HangCup、PlugInEthernet、OrganizeBookshelf、ConveyorSorting、ToolboxStorage、FoldTowel）：

| 任务 | `action.pivot` |
|---|---|
| HangCup / PlugInEthernet / OrganizeBookshelf / ConveyorSorting / ToolboxStorage | `[0,0,0,0,0.15,0,0.74]`，整段不变 |
| FoldTowel | `[0,0,0,0,0,0,0.74]`，第 5 维是 0 |

同时：

- `action.base_command = [0,0,0,0.74]`，整段不变。
- `action.waist_action_joint` 逐帧变化，但**不等于** `pivot[3:6]`；例如 HangCup 首帧 waist 是 `[-0.00998,-0.00373,0.18064]`，pivot 是 `[0,0,0,0,0.15,0,0.74]`。

**结论**：`pivot` 不是逐帧 waist 关节目标，更像任务级下身体/腰部姿态命令。最稳做法：先按任务输出数据集里的常数 `pivot`，只学双臂+夹爪；若单任务通道证明需要 waist 运动，再把 `pivot` 作为低方差 7D 头学习。不要猜 `pivot_3..5` 的符号。

## 2. 问题形式化

### 2.1 关节空间 chunk 策略

设观测 \(o_t\) 包含四路 RGB、双臂关节 \(q_t\in R^{14}\)、夹爪、`lower_body`、语言。策略：

\[
\pi_\theta:\ o_t \mapsto a_{t:t+H-1} \in R^{H\times 23}
\]

其中

\[
a_k = [q^{L}_k(7), q^{R}_k(7), g^{L}_k(1), g^{R}_k(1), p_k(7)]
\]

- \(q^{L/R}_k\)：绝对关节目标（rad），数据集顺序。
- \(g^{L/R}_k\)：夹爪绝对目标。
- \(p_k\)：`pivot`，先按任务常数。
- \(H\)：6–8（可扫描）。

训练目标：

\[
\mathcal{L} = \sum_{k=1}^{H} \| \hat a_k - a_k \|_1 + \lambda_v \sum_{k=2}^{H} \| \hat a_k - \hat a_{k-1} \|^2 + \lambda_g \mathcal{L}_{grip}
\]

可选辅助力矩回归：

\[
\mathcal{L}_{aux} = \sum_{k=1}^{H} \| \hat\tau_k - \tau_k^{RNEA} \|^2
\]

辅助头只用于训练正则；推理时力矩 verifier 直接用 RNEA，不依赖辅助头。

### 2.2 延迟模型

设控制频率 \(f_c\)，chunk 时长：

\[
T_{exec} = H/f_c
\]

推理时间：

\[
T_{inf} = T_{VLM}/K + T_{head} + T_{net}
\]

其中 \(K\) 是 VLM 特征缓存刷新周期（每 K 个 chunk 刷一次）。连续执行条件：

\[
H \ge f_c T_{inf}
\]

工程上留 20% 余量：

\[
T_{inf}^{p99} \le 0.8\,T_{exec}
\]

30 Hz 假设下：

| H | \(T_{exec}\) | p99 推理预算（80%） | 开环盲区 |
|---:|---:|---:|---:|
| 4 | 133 ms | 107 ms | 133 ms |
| 6 | 200 ms | 160 ms | 200 ms |
| 8 | 267 ms | 213 ms | 267 ms |
| 12 | 400 ms | 320 ms | 400 ms |
| 30 | 1000 ms | 800 ms | 1000 ms |

如果 WLA VLM 单次 300 ms、action head 30 ms、网络 20 ms：

- K=1：\(T_{inf}=350\) ms → H≥11；H=6 会每块停 150 ms。
- K=4：\(T_{inf}=75+30+20=125\) ms → H=6 连续，余量 75 ms。
- K=8：\(T_{inf}=37.5+30+20=87.5\) ms → H=4 也可连续，但特征更 stale。

**结论**：低延迟不是「模型更快」，而是「VLM 特征缓存 + action head 高频 + 下一 chunk 预计算」。缓存周期 K 是新的控制参数；接触段用 K=2，自由段用 K=4–8。

### 2.3 力矩可行性

逆动力学：

\[
\tau = M(q)\ddot q + C(q,\dot q)\dot q + g(q) + J_c(q)^T f_c
\]

\(f_c\) 未知。对候选 chunk，用有限差分得到 \(\dot q,\ddot q\)；物体负载按 \(m_p\in\{0,1,2\}\) kg 加在夹爪 frame，取最差/95 分位。归一化力矩：

\[
\tilde\tau_{k,i} = \tau_{k,i}/\tau_{max,i}
\]

力矩成本：

\[
J_\tau = \sum_{k=1}^{H}\sum_i \tilde\tau_{k,i}^2
\]

jerk 成本：

\[
J_{jerk} = \sum_{k=1}^{H}\| q_{k+1}-2q_k+q_{k-1}\|^2
\]

跟踪/信任域成本：

\[
J_{track} = \sum_{k=1}^{H}\| q_k - q_k^{ref}\|^2
\]

腕部裕度：

\[
m_k = \min_{i\in\{wrist\_yaw,wrist\_pitch\}} \left(1-|\tilde\tau_{k,i}|\right)
\]

\[
J_{wrist} = \sum_{k=1}^{H} \max(0, 0.3-m_k)^2
\]

总分：

\[
J = J_\tau + \alpha J_{track} + \beta J_{jerk} + \gamma J_{wrist}
\]

**注意**：\(J_\tau\) 是相对分数，不是绝对安全证书；物体质量/摩擦/URDF 误差都会让绝对力矩偏移。我们只用它做候选排序和软约束。

### 2.4 为什么关节空间可能优于 EE

| 环节 | EE 基线 | 关节空间 |
|---|---|---|
| 数据转换 | 关节→FK→EE 相对；工具坐标/TCP 误差 | 直接用 `action.left_arm/right_arm` |
| 推理→执行 | EE→IK→关节；奇异点/限位/冗余 | 直接关节目标；无 IK |
| 力矩检查 | EE 空间看不到腕部 5 N·m | 同一空间 RNEA；腕部裕度可见 |
| 泛化 | EE 目标对相机外参敏感 | 关节目标对相机外参不直接敏感 |
| 风险 | 关节轨迹可能不自然 | 可能过拟合关节配置 |

这不是「关节一定更好」，而是一个可检验假设（E1）。如果 E1 失败，回退 EE，保留 torque/compliance/anytime 的其他部分。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / joint chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)       │
                    │  ├─ joint action adapter (23D)      │
                    │  ├─ anytime scheduler + coast       │
                    │  ├─ torque verifier (RNEA/QP)       │
                    │  ├─ compliance (tracking error)     │
                    │  └─ wrist IBVS (optional)           │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared GPU server                  │
                    │  WLA VLM (cached) + joint DiT head  │
                    └─────────────────────────────────────┘
```

- 每个端口一个 `PolicyService` 实例，独立 `reset()`、独立 action queue、独立 compliance/IBVS 状态。
- 共享 GPU server 只共享权重；用 session ID 隔离 KV/cache；不共享动作状态。
- GPU server 可把 N 个端口的 action-head 请求做 batch；VLM 特征按端口缓存。
- 力矩 verifier/QP 在 CPU 上跑；14 关节 ×H=6 的 QP 很小，单端口 <5 ms 量级（需实测）。

### 3.3 关节动作适配

#### 3.3.1 数据集顺序 → 模型 → API

模型在数据集顺序上训练/推理：

```text
q_ds = [sp, sr, sy, e, wy, wr, wp]
```

RNEA/QP/Jacobian 用 URDF 顺序：

```text
q_urdf = q_ds[[0,1,2,3,5,6,4]]
```

API 返回用数据集顺序：

```text
action.left_arm  = (H,7) float32
action.right_arm = (H,7) float32
action.left_gripper  = (H,1) float32
action.right_gripper = (H,1) float32
action.pivot = (H,7) float32
meta.token = str
```

#### 3.3.2 夹爪

- 数据集 `action.left_gripper/right_gripper` 抽样约 4.5；先按数据集 min/max 归一化。
- API 的 `action.left_gripper/right_gripper` 只写“target left/right gripper command”，没有给范围/方向；必须在 `example_env.py`/单任务通道确认是 0–1 还是 0–5、开/合方向。
- 保守起步：输出数据集同尺度的绝对值；若 evaluator 拒绝或夹爪不动，再做 0–1 映射。

#### 3.3.3 `pivot`

- 先按任务输出常数：大多数任务 `[0,0,0,0,0.15,0,0.74]`，FoldTowel `[0,0,0,0,0,0,0.74]`。
- 任务到常数的映射用语言/任务名查表；这是 C1 离线索引，不是学习模型。
- 若单任务通道证明 evaluator 需要 waist 运动，再把 `pivot` 作为 7D 头学习；不要猜符号。

#### 3.3.4 形状/异常

- 返回前检查：dtype float32、shape `(H,7)`/`(H,1)`、finite、关节限位内、夹爪范围内。
- 任何异常 → 返回上一组合法 chunk 或安全 hold；绝不返回 NaN/错误形状。
- `meta.token` 每次都要带；token 错误会被 evaluator 拒绝。

### 3.4 `get_action` 伪代码

```python
class JoltPolicy:
    def get_action(self, obs):
        self._tick(obs)

        # 1) 取下一 chunk；没有就 coast
        if self.next_chunk is not None:
            chunk = self.next_chunk
            self.next_chunk = None
        else:
            chunk = self._coast(obs)

        # 2) 力矩筛选/投影（可选）
        if self.torque_enabled:
            chunk = self.verifier.select_or_project(chunk, obs)

        # 3) 跟踪误差柔顺
        if self.compliance_enabled:
            chunk = self.compliance.blend(chunk, obs)

        # 4) 腕部 IBVS（最后 3cm，可选）
        if self.ibvs_enabled and self.ibvs.gate(obs):
            chunk = self.ibvs.correct(chunk, obs)

        # 5) 异步计算下一 chunk
        self._launch_next(obs)

        return self.adapter.to_api(chunk, obs, self.token)

    def _launch_next(self, obs):
        if self.future is not None and not self.future.done():
            return
        if self.future is not None:
            self.next_chunk = self.future.result()
            self.future = None
        if self.next_chunk is None:
            snapshot = copy_obs(obs)
            self.future = self.executor.submit(self._compute_chunk, snapshot)

    def _compute_chunk(self, obs):
        # VLM 特征缓存：每 K 个 chunk 刷一次
        if self.vlm_cache is None or self.cache_age >= self.K:
            self.vlm_cache = self.vlm.encode(obs)
            self.cache_age = 0
        self.cache_age += 1

        # action head 采样 N 个候选
        candidates = self.head.sample(self.vlm_cache, obs, N=self.N)
        # 选最优（力矩/jerk/track）
        return self.verifier.rank(candidates, obs)
```

规则：

- VLA/action head 永远不阻塞 `get_action`（除冷启动）；冷启动超时就返回安全 hold。
- 每个 chunk 只做一次 verifier/compliance/IBVS；失败不影响返回合法动作。
- 任何异常 → 返回上一组合法 chunk 或安全 hold。
- 多端口并发时，GPU server 按 session 隔离；action head 可 batch，但 `reset()` 必须清掉该端口 cache。

### 3.5 状态机

```text
INIT ──first obs──▶ PLAN ──chunk ready──▶ TRACK
  ▲                   ▲                    │
  │                   │                    ├─ tracking error > eps ──▶ CONTACT
  │                   │                    │                           │
  │                   │                    │                           └─ error < eps/2 ──▶ TRACK
  │                   │                    │
  │                   └── replan ◀── RECOVER ◀── GEO edit or compliance trigger
  │                                      │
  └──────────────────────────────────────┘
任意状态 ──task success / max steps──▶ DONE
```

- `TRACK`：正常关节跟踪；力矩筛选开；IBVS 只在最后 3cm 开。
- `CONTACT`：跟踪误差触发；目标向测量位置 blend；chunk 缩到 2–3 步；必要时重规划。
- `RECOVER`：GEO 编辑检测或 compliance 持续触发；先停，再重定位/重规划。
- `DONE`：清理状态，等待 `reset()`。

## 4. 力矩可行性模块

### 4.1 RNEA 与归一化

用 Pinocchio（或 MuJoCo）加载 `g1_29dof_with_hand_rev_1_0.urdf`；先做关节置换；对每个候选 chunk：

1. 用当前 \(q_t,\dot q_t\) 和候选 \(q_{t+1:t+H}\) 做有限差分，得到 \(\dot q,\ddot q\)。
2. 对 \(m_p\in\{0,1,2\}\) kg 各跑一次 RNEA；取每个关节的最大 \(|\tau|\)。
3. 归一化：\(\tilde\tau_{k,i}=\tau_{k,i}/\tau_{max,i}\)。
4. 算 \(J_\tau,J_{jerk},J_{wrist}\)。

数值检查：

- 用 MuJoCo 同模型跑随机轨迹，比较 RNEA 与 MuJoCo `qfrc_inverse`；目标相对误差 ≤1%。
- 有限差分步长 1/30 s；对噪声做低通（Butterworth 2 阶，截止 10 Hz）。
- 末端负载用夹爪 frame 的 point mass；不要忽略手部质量。

### 4.2 负载不确定性

物体质量未知。做法：

- 三个假设 \(m_p=0,1,2\) kg；取每个关节的最大归一化力矩。
- 若任务已知物体类别（语言/视觉），可把 \(m_p\) 缩到 0–1 kg；但不要依赖。
- 力矩分数只做相对排序；不要用绝对阈值判断“安全”。
- 腕部裕度优先：即使 \(J_\tau\) 因负载偏差，腕部 5 N·m 的相对排序仍然有意义。

### 4.3 Best-of-N 选择

- 从 action head 采 N=2–4 个候选（不同噪声种子/不同 flow 初始噪声）。
- 每个候选算 \(J\)；选 \(n^*=\arg\min J\)。
- 若 N=1，跳过选择，只做 QP 投影。
- 候选多样性：如果 N 个候选几乎相同（pairwise L2 < 阈值），选择收益低；可以降 N 省算力。
- 延迟：N 个候选可以 batch 在 action head 里一次前向；不要串行跑 N 次 VLM。

### 4.4 QP 投影

变量：每个 chunk 的关节位置 \(q_{1:H}\in R^{H\times 14}\)（双臂），共 \(14H\) 个变量。目标：

\[
\min_{\Delta q}\ \|\Delta q\|^2 + \lambda\|D\Delta q\|^2 + \mu\|D^2\Delta q\|^2
\]

约束：

\[
q_{min}\le q^{ref}+\Delta q\le q_{max}
\]

\[
|\dot q^{ref}+D\Delta q/\Delta t|\le \dot q_{max}
\]

\[
|\tau(q^{ref})+J_\tau(q^{ref})\Delta q|\le 0.7\,\tau_{max}
\]

其中 \(J_\tau=\partial\tau/\partial q\) 是力矩对关节位置的雅可比（Pinocchio `computeJointTorqueRegressor` 或有限差分）。用 2–3 次 SQP：

1. 在当前 \(q^{ref}\) 算 \(\tau\) 和 \(J_\tau\)；
2. 解 QP 得 \(\Delta q\)；
3. 更新 \(q^{ref}\leftarrow q^{ref}+\Delta q\)；
4. 重复 2–3 次，取最后一次可行解。

实现：

- `osqp`/`quadprog`/`qpsolvers` 都可；问题规模小（H=6 → 84 变量）。
- 若 QP 超时（>10 ms），退回 best-of-N 或只做速度/限位 clip。
- QP 不改变 chunk 的语义，只把不可行候选拉回可行域；信任域限制 \(\|\Delta q\|\) 防止拉得太远。

### 4.5 腕部力矩裕度与任务排序

E0 对 32 任务演示轨迹算 RNEA（\(m_p=0,1,2\)），统计：

- `wrist_yaw`/`wrist_pitch` 的 \(m_k\) 分布（p5/p50/p95）；
- 肩/肘峰值力矩；
- 高 jerk 帧比例；
- 接触动词/阶段（先验）。

排序分数：

\[
\text{priority}_t = \frac{\text{wrist\_demand}_t \times \text{contact\_density}_t \times \text{gap}_t}{\text{cost}_t}
\]

- `wrist_demand`：腕部 \(m_k<0.3\) 的帧比例；
- `contact_density`：任务文本/演示中的接触阶段比例（先验）；
- `gap`：当前成功率缺口（单任务通道/基线）；
- `cost`：工程/评测成本。

预期 A 档：Unlock、PourOutMedicine、ZipUp、PlugInEthernet、HangCup、ArrangeTestTubes、PlugCharger、StackBowls。FoldTowel 放 B 档做回归守卫（pivot 第 5 维=0，变形任务）。

### 4.6 位置基柔顺

定义加权跟踪误差：

\[
e_q = W(q_{cmd}-q_{meas})
\]

\(W=\mathrm{diag}(1/\text{range}_i)\)。触发：

\[
\|e_q\| > \epsilon \text{ for } K \text{ frames}
\]

柔顺系数：

\[
\alpha = \mathrm{clip}\left(\frac{\|e_q\|-\epsilon}{\delta},0,\alpha_{max}\right)
\]

目标混合：

\[
q_{cmd}' = (1-\alpha)q_{policy}+\alpha q_{meas}
\]

- 起步 \(\epsilon=0.1\)（归一化），\(K=3\)，\(\alpha_{max}=0.8\)。
- 触发后 chunk 缩到 2–3 步；若持续触发 >10 帧，进入 RECOVER。
- 释放：\(\|e_q\|<\epsilon/2\) 时 \(\alpha\to0\)。
- 这是位置基阻抗；有效刚度约 \((1-\alpha)K_p\)。不发力矩。

### 4.7 数值/工程检查

- 关节置换：单元测试 `q_ds[[0,1,2,3,5,6,4]]` 与 URDF 关节名逐一对齐。
- 力矩符号/单位：URDF 是 N·m；Pinocchio 输出 N·m；确认没有 mNm/ratio 混淆。
- 有限差分噪声：先低通再差分；对 30Hz 数据，差分对噪声敏感。
- 负载模型：point mass 在夹爪 frame；不要重复计算手部质量。
- QP 可行性：如果无解，放宽力矩约束到 0.9/1.0，或只做限位/速度 clip；不要返回 NaN。
- 力矩 verifier 的耗时：目标 <5 ms/候选；N=4 时 <20 ms；需实测。

## 5. 低延迟执行

### 5.1 管线与 deadline

一次 `get_action` 的时间线：

```text
t0: evaluator 调用 get_action(obs_t)
t0: 返回 chunk k（已预计算）
t0..t0+T_exec: evaluator 执行 chunk k
t0: 后台开始算 chunk k+1（用 obs_t 或稍新的 obs）
t0+T_exec: evaluator 再次调用 get_action(obs_{t+H})
```

如果 \(T_{inf}\le T_{exec}\)，chunk k+1 在下次调用前就绪；否则用 coast。

- 冷启动：第一次 `get_action` 必须同步算一个 chunk；若超时，返回安全 hold（当前关节位置重复 H 次）。
- 预计算：每次返回 chunk 后立刻启动下一 chunk 的异步计算；不要等下一次调用。
- 超时：`future.result(timeout=T_exec*0.9)`；超时就 coast。
- 多端口：GPU server 用队列/batch；不要让一个端口的长推理阻塞其他端口。

### 5.2 Coast/blend

Coast chunk：

\[
q_{t+k} = \mathrm{clip}\left(q_t + k\Delta t\,\dot q_t^{lp},\ q_{min},q_{max}\right)
\]

- \(\dot q_t^{lp}\) 是低通后的测量速度；不要用指令速度（可能含噪声）。
- 夹爪保持上一指令；pivot 保持常数。
- 新 chunk 到达后，前 2–3 步线性 blend：

\[
q_k^{blend} = (1-\beta_k)q_k^{coast}+\beta_k q_k^{new},\quad \beta_k=k/3
\]

- 如果 coast 与 new 的差 > 阈值（如 0.3 rad），不要硬 blend；先 hold 一帧再切，或触发重规划。
- Coast 只用于“下一 chunk 未就绪”的短窗口；不要长期 coast。

### 5.3 Chunk size 扫描

- H ∈ {4,6,8,12,30}；每个 H 测 p50/p99 推理、暂停时长、成功率、步骤分。
- 选择规则：在成功率不低于最佳 1pp 的前提下，选最小 H；若 H=4 的 p99 超预算，选 H=6/8。
- H 固定写在 `metadata.action_chunk_size`；不能在 episode 中改（evaluator 按 metadata 校验）。
- 如果 evaluator 控制频率不是 30Hz，按实测 \(f_c\) 重算 \(T_{exec}\)；不要假设。

### 5.4 计算预算（示例，需实测）

假设单张 24GB GPU，WLA 6B bf16，VLM 300 ms，action head 30 ms，网络 20 ms：

| 配置 | VLM 频率 | N | 估算 \(T_{inf}\) | H=6 是否连续 |
|---|---|---:|---:|---|
| 无缓存 | 每 chunk | 1 | 350 ms | 否（停 150 ms） |
| K=4 | 每 4 chunk | 1 | 125 ms | 是（余量 75 ms） |
| K=4 | 每 4 chunk | 4（batch） | 125 + 3×30 = 215 ms | 否（略超） |
| K=2 | 每 2 chunk | 4（batch） | 150 + 90 + 20 = 260 ms | 否 |
| K=4 + 量化 | 每 4 chunk | 4 | 可能 150–180 ms | 边缘 |

**结论**：N=4 的 best-of-N 与 H=6 的延迟预算会打架。优先级：

1. 先做 N=1 + QP/软约束（最省算力）；
2. 若 E3 证明 best-of-N 有收益，再降 VLM 频率/量化/换小基座；
3. 或者 H=8（267 ms）给 N=4 留空间，但开环盲区变大。

### 5.5 失败处理

- 推理超时 → coast；连续 2 次超时 → 增大 H 或降 N（若 metadata 允许）或返回 hold。
- NaN/形状错误 → 回退上一组合法 chunk；记录日志。
- token 错误 → 立即返回带正确 token 的动作；不要重试握手。
- evaluator 断开 → 清理该端口状态；等待重连。
- 多端口内存 → 每个端口只保留一个 VLM cache/一个 future；不要无限堆。

## 6. 腕部视觉伺服

### 6.1 内参与去畸变

- 使用 1.3.4 的 `wrist_left/right.color` 内参。
- 畸变模型是 `distortion.inverse_brown_conrady`；先确认图像是否已去畸变：
  - 若图像是 raw：用逆 Brown-Conrady 模型去畸变；
  - 若图像已去畸变：系数可能是“逆”系数，不要再重复去畸变。
- 验证：用棋盘格/直线，检查重投影误差 ≤5 px。

### 6.2 手眼标定

URDF 没有腕部相机 frame，所以需要一次手眼标定：

1. 打印/放置棋盘格，固定在桌面上；
2. 机械臂走 20 个不同姿态，每个姿态记录关节角 + 腕部图像；
3. `cv2.findChessboardCorners` + `cv2.calibrateCamera` 得到每帧 `T_target_cam`；
4. 正运动学得到 `T_base_ee`；
5. 解 \(AX=XB\)（`cv2.calibrateHandEye`），得到 `T_ee_cam`；
6. 验证：留出 5 个姿态，重投影误差 ≤5 px。

如果没有真机：

- 用 Dex1 CAD/装配图的 nominal mount 作为初值；
- 用数据集头双目 + 腕部图像做离线联合标定（头双目看到腕部相机/夹爪，三角化后转 base）；
- 或者直接用在线 Broyden，跳过外参。

### 6.3 IBVS 控制律

点特征 \(s=(u,v)\)，归一化坐标 \(x=(u-c_x)/f_x,\ y=(v-c_y)/f_y\)。交互矩阵（2×6）：

\[
L_s = \begin{bmatrix}
-f/Z & 0 & x/Z & xy/f & -(f^2+x^2)/f & y\\
0 & -f/Z & y/Z & (f^2+y^2)/f & -xy/f & -x
\end{bmatrix}
\]

相机到 EE 的 adjoint \(T_{cam}^{ee}\)；臂雅可比 \(J_{arm}(q)\)（6×7，URDF 顺序）。特征雅可比：

\[
J_s = L_s\,\mathrm{Ad}(T_{cam}^{ee})\,J_{arm}(q)
\]

控制：

\[
\Delta q = -\lambda (J_s^T J_s + \mu I)^{-1} J_s^T e
\]

- \(e=s-s^*\)；\(s^*\) 来自 DG-KEYFRAME 目标腕部图。
- 只对最后 3cm 启用；\(\|\Delta q\|\) 限幅（如 0.05 rad/步）。
- 深度 \(Z\) 用夹爪到物体的 nominal 距离（0.1–0.3 m）或从 EE 位姿/物体模型估计；不要用单目深度网络（第二个模型）。
- 置信度：特征匹配数、RANSAC inlier、重投影误差；低于阈值就关闭 IBVS。

### 6.4 在线图像雅可比（无外参兜底）

如果手眼标定不可用：

\[
\Delta s_t = J_t \Delta q_t
\]

Broyden 更新：

\[
J_{t+1}=J_t+\frac{(\Delta s_t-J_t\Delta q_t)\Delta q_t^T}{\|\Delta q_t\|^2+\epsilon}
\]

- 只在 \(\|\Delta q_t\|>0.01\) rad 时更新；小步冻结。
- 用阻尼最小二乘求 \(\Delta q\)；加关节限位/步长限幅。
- 初始 \(J\) 可以用 nominal 外参/URDF 给一个粗值；也可以从零开始，前几个探索步收敛。
- 这是确定性自适应控制器，不是学习模型。

### 6.5 目标检索与置信度

- 目标特征来自第 12 轮 DG-KEYFRAME：从成功演示里检索“受器→夹爪”相对位姿 + 腕部目标图。
- 检索键：任务/阶段/语言/当前 VLM 特征/物体检测框；top-k 重打分。
- 特征：ORB/SIFT、颜色直方图、轮廓/边缘；透明/反光物体用边缘/深度梯度。
- 置信度低 → 只用策略；不要用错误目标做伺服。
- 目标被夹爪挡住 → 用头双目 PBVS 或纯策略；不要硬匹配。

### 6.6 安全/限幅

- 关节限位、速度限位、步长限幅；IBVS 修正量不要超过策略 chunk 的 20%。
- 跟踪误差触发时关闭 IBVS，先柔顺/停。
- 最大连续 IBVS 步数（如 30 步）；超过就重规划。
- 任何异常 → 回退策略 chunk。

### 7.1 WLA action head 改造

1. 复制 `unifolm_wla_action_adapter.py`，新增关节槽位：
   - `left_arm` [7]、`right_arm` [7]；
   - 保留 `left_gripper`/`right_gripper`；
   - `pivot` [7]（或 `waist_joint`+`base_command` 的组合）。
2. 修改 `unitree.yaml` 的 `action_keys`，让 Dex1 数据加载 `action.left_arm/right_arm/left_gripper/right_gripper/pivot`。
3. 修改 DiT 输出投影：54D → 23D；新投影小随机初始化/零初始化；其余层从 base checkpoint 加载。
4. 冻结 VLM（`trainer.freeze_modules: qwen_vl_interface`），只训 DiT + state projector。
5. 单张 24GB 先跑 batch=1/2；监控显存/NaN。

### 7.2 归一化与 chunk

- 逐关节 mean/std 从 32 任务训练集统计；夹爪单独统计；pivot 用任务常数或小方差。
- 归一化到 [-1,1] 或 [-3,3]；推理时用同一统计量反归一化。
- Chunk H=6–8；训练目标取未来 H 帧；episode 末尾 pad + mask。
- 动作绝对目标；不要训练 delta（数据集是绝对目标，delta 会引入累计误差）。
- 速度/加速度用有限差分 + 低通；训练时可加平滑损失。

### 7.3 损失

\[
\mathcal{L} = \mathcal{L}_{joint} + \lambda_v\mathcal{L}_{vel} + \lambda_g\mathcal{L}_{grip} + \lambda_\tau\mathcal{L}_{aux}
\]

- \(\mathcal{L}_{joint}\)：L1 或 Huber，对 14 个关节。
- \(\mathcal{L}_{vel}\)：相邻 chunk 步的速度差；减少抖动。
- \(\mathcal{L}_{grip}\)：MSE/BCE，按夹爪范围。
- \(\mathcal{L}_{aux}\)：可选，预测归一化力矩；标签用 RNEA（\(m_p=0,1,2\) 取最大）。辅助头只训练用。

### 7.4 增强与泛化

- 位置泛化：物体/目标位置抖动；若只有真实数据，用图像裁剪/平移模拟小偏移。
- 干扰物：随机贴图/物体叠加；不要遮挡关键接触区域。
- 背景：桌布颜色/纹理替换；颜色抖动。
- 未见物品：VLM 语义；关节动作对物体外观不敏感。
- 人为干扰：compliance + 重规划；训练时可加“目标被移动”的演示增强（若有）。
- 关节噪声：对当前关节状态加小高斯噪声；对动作目标加小噪声（不要破坏接触相位）。
- 时间缩放：0.9–1.1×；不要过度。

### 7.5 划分与指标

- 按 session/物体/背景分组划分；禁止相邻帧跨 split。
- 离线指标：chunk MSE、DTW、关节限位违规率、力矩裕度分布、jerk。
- 真机指标：成功率、步骤分、耗时、p99 推理、暂停时长、跟踪误差峰值。
- 单任务通道：每个任务 5–10 次配对 A/B；报告均值 + bootstrap CI。

### 8.2 门 G0–G8

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | 关节/动作映射是否正确？ | 离线回放 action≈next state；置换后 RNEA 与 MuJoCo ≤1%；pivot 常数被接受 | 只做双臂，pivot 回零；检查 `example_env.py` |

### 8.3 统计与样本量

- 320 trials 下 \(p\approx0.25\) 的单次标准误约 2.42pp；配对设计更低。
- 单任务 5 次 A/B 只能看大效应（≥20pp）；10 次才能看 10pp 量级。
- 报告均值 + bootstrap 95% CI；不要只报“涨了”。
- 多任务比较用分层/bootstrap；不要把 32 个任务当独立同分布。
- 若只能做 5 次/任务，把结论写成“方向性证据”，不要写成“显著”。

## 9. 竞赛策略

### 9.1 任务组合

| 档 | 任务 | 投什么 | 不投什么 |
|---|---|---|---|
| A（力矩/接触） | Unlock、PourOutMedicine、ZipUp、PlugInEthernet、HangCup、ArrangeTestTubes、PlugCharger、StackBowls | 关节直控 + 力矩筛选 + compliance + 腕部 IBVS | 更大 VLA、更多语义数据 |
| B（回归/变形） | FoldTowel、PackBag、StorePaddle、OrganizeStationery | 关节基线 + compliance；FoldTowel 作回归守卫 | 激进力矩筛选 |
| C（语义/长程） | FruitSorting、ColorArrangement、SpellRobot、ConveyorSorting | VLA 基线；只做数据增强 | 关节/力矩大改 |

E0 跑完后用真实腕部力矩裕度重排；不要用预览榜单任务排名。

### 9.2 单任务通道协议

1. 选 5 个代表任务：PlugInEthernet、HangCup、Unlock、ZipUp、FoldTowel。
2. 每个任务 5 次配对 A/B：
   - EE 基线 vs 关节；
   - H=30 vs H=6/8；
   - torque off/on；
   - compliance off/on；
   - wrist IBVS off/on。
3. 记录成功、步骤分、耗时、p99 推理、暂停时长、跟踪误差峰值。
4. 通过标准：3/5 任务 +10pp；FoldTowel 不回归 >5pp；p99 推理 ≤0.8 T_exec。
5. 再扫 H/N；选延迟/成功率最佳折中。

### 9.3 提交节奏

1. **安全基线**：官方 WLA EE、H=30、pivot 常数、无 joint/torque。先交，锁“更早提交” tie-break。
2. **关节版**：WLA joint head、H=6/8、无 torque/QP；E1 过门才交。
3. **力矩/compliance 版**：E3/E4 过门才交。
4. **全量版**：E5/E6 过门才交；不要在 320 trials 上试未过门组合。
5. 若提交次数未知，先邮件确认；不要烧掉唯一提交。

### 9.4 资源与时间表

- GPU：单张 24GB 可微调 WLA；推理可能需要 1–2 张（VLM + action head/多端口）。
- CPU：每端口一个 PolicyService；力矩/QP/IBVS 轻量；N 端口并发需压测。
- 数据：32 任务约 33k episodes；离线缓存/视频解码是瓶颈；先做子集（5 任务）跑通。
- 时间：E0 1 周；E1 2 周；E2/E3 2 周；E4/E5 2 周；E6/E7 2 周；留 2 周缓冲。

## 10. 风险与合规

### 10.1 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 关节空间过拟合 | 位置/背景泛化变差 | 图像/关节噪声增强；按 session 划分；E6 五轴验证 |
| 物体质量未知 | 力矩分数偏差 | 0/1/2 kg 最坏情况；只用相对排序；腕部裕度优先 |
| URDF 与实际 G1 不一致 | RNEA 误差 | MuJoCo/Pinocchio 校验；跟踪误差在线校正；力矩不作硬安全保证 |
| 腕部外参缺失 | IBVS 方向错 | 手眼标定；在线 Broyden 兜底；置信度低退回策略 |
| `pivot` 语义不明 | 下身体不动/错误 | 先用数据集常数；单任务通道验证；不猜符号 |
| 单模型解释 | 被判定第二个模型 | joint head 同一 checkpoint；verifier/QP/compliance/IBVS 无学习权重；文档写清 C1/C2/C3 |
| VLM 6B 太慢 | H=6 仍暂停 | 特征缓存；量化/蒸馏；换小基座；H 扫描 |
| 评测频率未知 | chunk 时长算错 | 单任务通道测 \(f_c\)；按实测重选 H |
| 关节动作噪声 | 抖动/超限 | 低通/限幅/QP；chunk blend；速度约束 |
| 安全 | 碰撞/过载 | 力矩/速度/限位约束；跟踪误差即停；最大重试 |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组；相邻帧不跨 split |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |

### 10.2 单模型合规

沿用第 12 轮的三种模式：

- **C1**：离线标注/检索索引（DG-KEYFRAME、任务→pivot 常数），不参与在线推理。
- **C2**：确定性控制器（RNEA verifier、QP、compliance、IBVS），无学习权重。
- **C3**：同一 checkpoint 的 joint action head；不加载第二个学习策略/残差网络。

提交材料明确：

- 唯一学习模型 = WLA VLM + joint DiT head（一个 checkpoint）。
- 力矩 verifier 用 URDF + 当前状态，不学习。
- QP/compliance/IBVS 是控制器，不是模型。
- 任务→pivot 常数是离线查表，不是模型。

### 10.3 安全

- 关节限位/速度限位/力矩软约束；QP 无解时退回限幅。
- 跟踪误差持续触发 → 停/回退；不要硬推。
- 最大重试/最大步数；超时失败要优雅退出。
- 多端口隔离；`reset()` 清 cache/queue/compliance 状态。
- 不要在未验证的物体质量/外参下开高增益 IBVS。
