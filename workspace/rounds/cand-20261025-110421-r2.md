# 第 8 轮（研究循环第 2 轮）· WRIST-MAP：腕部是近场度量锚点，SLAM 是桌面物体账本，步态是受限姿态恢复

> 检索/复核日期：**2026-10-25（UTC）**。赛事身份不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署、官方远程真机 API 评测。本轮三个灵感词是「腕部相机」「同步定位与建图」「步态规划」。我先用官方手册和数据集把三个词各自钉到事实上，再给出一个把上一轮 PILOT 从「单帧 grounding」升级为「每 episode 状态估计」的合成方案：**WRIST-MAP = 头双目锚定的腕部自标定（SAWC）+ 桌面物体位姿账本（TAOM）+ 腕部视角规范化（WVC）+ 姿态优先/底盘最后的主动感知（BAP）**。步态被有意降级：它不是主线，而是最后手段。

## 0. 先纠正上一轮的四个关键事实

### 0.1 排名公式：成功率优先，步骤分只是 tie-break

官方中文手册写得很清楚：**实时榜单按 32 个任务的总平均成功率排序；成功率相同时按总平均步骤分排序；仍相同则提交日期早者靠前**（[S1]，英文版 [S2] 同义）。这直接修正了上一轮的一个隐含权重：上一轮把「放置类步骤约占 59.7% 步骤分」当成主收益，但**步骤分只在成功率并列时决定名次**。终局放置仍然是闸门，理由却要改写：

```text
上一轮：终局放置重要，因为它占步骤分 39.8% / 放置类约 59.7%
本轮：  终局放置重要，因为它决定 binary success；
        步骤分是诊断与 tie-break，不是主 objective。
```

这不是文字游戏。它意味着：**任何只提高部分步骤、但不能把 episode 从 fail 变成 success 的模块，都应降权**；而「让一个 0% 任务开始有成功」「让 human 轴撤销后能恢复」这类能力，权重上升。SSG 仍然保留，但从「部分分优化器」改成「诊断 + 恢复触发器」。

### 0.2 「榜首不到 30%」目前是占位数据，不是真实榜单

截至 **2026-10-25 10:42 UTC**，官方 `leaderboard.html` 仍是「即将发布 / Coming Soon」，`runs.html` 仍是 `256 / 256` 占位记录（[S10][S11][S12]）。`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，里面 8 个模型的首位是 `MolmoAct2 / DexHacker`：成功率 **29.7%**、步骤分 **39.0**、平均时长 **44.02s**（[S11]）。用户说的「榜首成功率也不到 30%」与这个 29.7% 完全吻合，因此**它很可能来自占位数据，而不是真实评测**。

所以本轮不把「<30%」当事实，而把它当待验证假设：

- 如果真实榜首确实 <30%，最可能的瓶颈不是模型容量，而是**闭环状态估计与恢复**（见 §3）；
- 如果真实榜首高于 30%，说明公开基线族中被低估的工程/数据因素在起作用，本轮的状态层仍然是增量，但收益上限要重估；
- 搜索还出现了 RoboChallenge Table 30 V2 的 43.33%（LoopWAM），但那是**另一个 benchmark**，不能拿来当 UniBot 的上限（[S31]）。

这也是本轮的第一个研究动作：**先建立「榜单观察协议」**，等真实数据发布后用同一套诊断脚本复核，而不是在占位数据上推理。

### 0.3 10 次/任务、5 类泛化各 2 次、180 秒

中文手册：每个任务执行 **10 次独立运行**，5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰）**各出现 2 次**；单次真机执行最大 **180 秒**，超时记失败（[S1]）。这给出一个比上一轮更锋利的组合算术：

| 量 | 数值 | 含义 |
|---|---:|---|
| 总评测次数 | 32 × 10 = **320** | 成功率的样本量 |
| 单任务权重 | 10/320 = **3.125pp** | 一个任务从 0% 到 100%，总分 +3.125pp |
| 单泛化轴权重 | 64/320 = **20%** | 某一轴全线失败，最多损失 20pp |
| 总体成功率标准误（p≈0.3） | **≈2.56pp** | +3pp 约 1.2 SE，统计上并不稳 |
| 一个任务 catastrophic zero | **−3.125pp** | 5 个任务全零，直接 −15.6pp |

因此本轮的预算逻辑是：**先消除 catastrophic zeros，再攻跨轴终局能力，最后才做 steps 微调**。这比上一轮的「放置优先」更完整：放置是跨轴杠杆，task-zero triage 是组合杠杆，human 轴恢复是 20% 权重的专项杠杆。

### 0.4 `action.pivot` 存在，但演示是「固定底座 + 少量姿态变化」

提交接口要求每个 chunk 都返回 `action.pivot [7]`，数据集里的定义是 **`[vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]`**（[S4][S6]）。我抽样了 8 个任务、每个 200 帧（HangCup、ConveyorSorting、StackBowls、OrganizeBookshelf、PackBag、FoldTowel、OrganizePencilCase、PlugCharger）：

- **`vx / vy / angle_z` 全部为 0**；
- 多数任务 `height = 0.74`、`pivot_4 = 0.15`；
- 只有 **FoldTowel** 的 `height` 在 **0.7116–0.74** 之间变化，且 `pivot_4 = 0`；
- `pivot_3 / pivot_5` 在所有抽样中为 0。

结论要说得精确：**在这 8 个任务里，底盘平移/旋转是 OOD；高度/躯干姿态在 FoldTowel 里有演示，属于部分分布内**。因此「步态规划」在 UniBot 桌面任务里不是一个可以直接端到端学习的动作，而是：

1. **姿态优先**：`height`、`pivot_4`（疑似躯干/腰部姿态）是安全、连续、部分在分布内的主动视角自由度；
2. **底盘最后**：`vx/vy/angle_z` 只在目标不可达、遮挡严重、且调试槽证明评测器真的执行 pivot 时才用；
3. **不做足端规划**：API 只给 base command，底层步态由控制器负责；在策略侧做 footstep RL 既 OOD 又浪费 180s。

这比上一轮把 FLEET 当「第六轴」更克制：**步态是受限恢复，不是研究主轴**。

### 0.5 腕部相机有内参、没有外参；头部双目才是度量锚点

数据集 `camera_params`（[S6]）给出：

- **头部双目**：已矫正，基线 `T = -58.25mm`，左右内参/畸变齐全；
- **腕部左右**：彩色内参（f≈436）+ 畸变，以及 IR 内参/IR-to-color 外参；
- **没有腕部相机到 EE / base 的外参**。

这正好是「腕部相机」这个灵感词的技术入口：腕部不是「第五路 RGB」，而是一台**没有标定的近场单目相机**。头部双目有度量基线，腕部有近场细节；两者在抓取/放置过程中会看到同一个目标。于是可以做**头双目锚定的腕部自标定（SAWC）**：用头部双目三角化出 3D 点，用腕部图像上的对应 2D 点做 PnP，解出腕部相机在 base 的位姿，再用 EE 位姿解出手眼变换 `T_E_C`。离线在 33k 演示上做一次，线上用第一次伸手做小幅 refine。

另外两个接口事实让这个方案更可行：

- 头部相机位姿在数据里是 `state_d435`，但**不在提交观测目录里**；提交只给 `lower_body`（15 维，含 waist yaw/roll/pitch）；
- 头部相机位姿在一个 episode 内并非完全固定：HangCup 抽样中 `state_d435` 的 x 变化约 **1.9cm**、z 约 **0.5cm**、pitch 约 **2.6°**，与腰部姿态相关。

所以线上不能假设头相机位姿恒定，而要用 **`lower_body` 腰部关节 + 离线拟合的 `T_torso_H`** 恢复头部位姿；误差约几毫米/零点几度，足够支撑厘米级放置。这个「API 没给、但可以用本体感知恢复」的细节，是本轮工程创新的关键。

### 0.6 公开基线族的真实形态：6B + 全量 33k + LoRA，开环指标很好，闭环未知

公开可查的 UniBot LoRA 方案（[S13]）：

- **LingBot-VLA 2.0**：6.3B（Qwen3-VL-4B + Qwen2 action expert + MoE），LoRA rank 64/alpha 32 只训 q/v/o，65M 可训练参数；
- 全量 **32 任务 / 33,276 episodes**，10K steps，单卡 **RTX 4090**，bf16；
- joint 控制（arms 14、grippers 2、waist 4、base 3 的 canonical 空间）；
- 只报了开环 `val/loss 0.085` 与 ArrangePlates 的 MSE 0.229 / MAE 0.176，**没有闭环成功率**；
- 50-step chunk 在 4090 上约 **0.35s**。

这类方案的代表性很强：**算力不是门槛，全量数据 + 6B 底座 + LoRA 已经是公开可复现的基线**。它最可能的瓶颈不是「模型不够大」，而是：

1. 开环 loss 与闭环 success 脱节；
2. 没有显式物体状态，遮挡/人为移动后只能重新 grounding；
3. 腕部相机被当普通 RGB，没有度量标定；
4. 没有恢复策略，human 轴「撤销」直接把已完成的步骤打回；
5. 32 任务里少数 catastrophic zeros 拉低总平均。

这五条正好对应本轮 WRIST-MAP 的五个切入点。

## 1. 三个灵感词，各自钉到官方事实上

### 1.1 腕部相机：不是第三只眼，是近场度量传感器

把腕部当「多一路 RGB」是基线做法；本轮要把它变成「可标定的近场传感器」。证据链：

- **SaPaVe（CVPR 2026）** 在同一架构下做了干净的相机消融：固定相机 **36.17%** → 固定 + 腕部 **52.33%** → 主动相机 + 腕部 **73.16%**；真机上 π0 **45.0%**、GR00T-N1 **53.75%**、其方法 **85.0%**（[S15]）。腕部和主动视角是两个独立增益，不是冗余。
- **WARP-VLA**：腕部视角扰动下 π0.5 从 **39.2% → 78.3%**；腕部相机随手臂运动，安装误差会改变细粒度几何线索，跨机部署几乎不可能复现训练时的精确外参（[S16]）。
- **Cloak**：腕部视野里末端执行器占很大且一致的区域，把它 mask 掉反而让 VLA 学到与 embodiment 无关的视觉推理，零样本迁移到新夹爪/机械臂/五指手（[S25]）。
- **ActivePose**：用腕部相机做主动 6D 位姿估计与跟踪，VLM 判断视角歧义，再用 next-best-view 消歧（[S24]）。

映射到 UniBot：

- 腕部负责**近场**：最后 3cm 的放置、插入、闭合、settle 验证；
- 头部双目负责**度量锚点**：把腕部的相对几何锚到 base 系；
- 腕部外参靠 SAWC 离线标定 + 首次伸手在线 refine；
- 腕部图像做 WVC（去畸变、尺度/方向规范化、夹爪 mask），减少跨机安装差异。

一句话：**基线把腕部当观测；我们把腕部当测量。**

### 1.2 SLAM：不是建整屋地图，是建桌面物体账本

「SLAM」在桌面任务里听起来过重，但把问题拆开，它恰好是四个组件的组合：

| SLAM 组件 | 桌面任务里的对应物 |
|---|---|
| 机器人定位 | base 固定；头部位姿由 `lower_body` 腰部 FK 恢复；腕部位姿由 EE + SAWC 恢复 |
| 地图 | 每 episode 的物体/容器位姿图（10 个左右节点） |
| 数据关联 | 相同碗/杯/积木的实例匹配（颜色、尺寸、空间连续性、SSG 步骤顺序） |
| 回环/重观测 | 遮挡后重新看到物体、人的干扰后重新定位 |
| 变化检测 | 人把物体平移、把已叠好的碗拿走、把拉链拉开 |

证据链也很直接：

- **Ledger**：把长期物体记忆放在策略外部，做成显式可读的 spatio-temporal object memory；在 RoboMME 上 64.3% vs 最强 prior 45.9%，object reference 60.7% vs 40.3%，object permanence **86.7% vs 56.2%**（[S18]）。这证明「外部账本 + 内部短时记忆」的分工是有效的。
- **OASIS-Map**：多 session 的 object-level change detection，用 patch-level semantic correspondence 做变化检测与物体关联；car replacement F1 **0.783**，3RScan moved object association F1 **0.667**（[S19]）。
- **DAF object SLAM**：data-association-free，联合估计位姿、landmark、语义，专门处理「测量与 landmark 关联错」这个核心问题（[S20]）。
- **LLM-Enhanced Object SLAM**：用 LLM 提供物体尺寸/朝向先验，在稀疏观测下把 mapping accuracy 提升 **36.8%**（[S21]）。
- **EchoVLA**：scene memory（spatial-semantic map）+ episodic memory，mobile manipulation 比 π0.5 高 +0.20/+0.11（[S22]）。

映射到 UniBot 的 human 轴：官方备注几乎都是「把某物平移」「某步完成后撤销」（T27 叠了第二个再拿走、T19 拉上后再拉开、T14 拧开后再拧回、T24 可乐快到了再放回起点）——**这不是新的语言指令，而是状态变化**。如果模型每次都重新 grounding，它会把「已经完成的步骤」当成「没完成」，或者去追一个已经不在原位的物体。**账本 + 变化检测 + SSG 回滚**是对这个轴的直接解。

### 1.3 步态规划：姿态优先，底盘最后

步态的证据链很强，但方向和 UniBot 的接口不匹配：

- **STRIDER**：多步态层级 3D loco-manipulation，foothold tracking + AMP 自然行走 + 笛卡尔上半身控制，在 TianGong Omni 真机上实现多步态 loco-manipulation（[S26]）。
- **Reachability maps**：把 footstep/grasp 的交替与顺序做成图搜索，用可迁移的 reachability map 评估（[S27]）。
- **B\***：固定底座机械臂的最优 base placement，把 base 当额外 3 DoF 做优化（[S28]）。
- **ULC**：统一 fine-grained humanoid loco-manipulation 控制器，同时追 tracking accuracy、large workspace、robustness（[S29]）。
- **SaPaVe** 的主动相机 + 腕部增益说明「改变视角」本身值 +20.8pp；**ActiveAlign** 又给出警告：朴素地先动相机再交给未对齐的 VLA，会把 LIBERO 的 46.3% 打到 **11.5%**；用 post-move 状态对齐训练后可到 70.7%/72.7%，真机遮挡 35/90 → 83/90（[S17]）。

映射到 UniBot：

- **不要走路**：演示里 base 平移/旋转为 0，走路是 OOD；180s 也不允许频繁走；
- **先用姿态**：`height`（FoldTowel 已证明有分布内变化）和 `pivot_4`（疑似躯干/腰部）是更安全的主动视角；
- **底盘只做小步恢复**：`vx/vy` ±3–5cm、`angle_z` ±5–10°，最多 2 次，且必须先做 pivot 语义探针；
- **必须做观测对齐**：BAP 之后要么用确定性 SVL 收尾，要么在 post-move 状态上微调 VLA；否则就是 ActiveAlign 的 46.3→11.5 陷阱。

一句话：**灵感词「步态规划」在本赛事里应该被翻译成「姿态/底盘作为受限主动感知」，而不是「学会走路」。**

## 2. 本轮主判断：从「单帧 grounding」升级为「每 episode 状态估计」

上一轮 PILOT 的六个失败模式里，P1（落点 grounding 错）、P3（姿态不对）、P4（释放过早）、P6（不验证就以为完成）看起来是四个问题；本轮把它们统一成一个更锋利的失败模型：

```text
P1/P3/P4/P6 的本质不是「当前帧没看清」，
而是「机器人没有维护一个跨帧的物体/容器状态」。
- 人把碗移走 → 状态没更新 → 还往旧位置放（P1）
- 自己手臂挡住目标 → 状态丢了 → 重新猜（P1/P6）
- 放置后物体弹跳/滚动 → 没有 settle 状态 → 以为完成（P4/P6）
- 已叠好的碗被拿走 → 步骤状态没回滚 → 继续叠第三个（P3）
```

于是本轮的主判断是：

> **把 PILOT 的「单帧目标 → 动作」改成「单帧观测 → 状态更新 → 目标 → 动作」。**
> 状态层就是 WRIST-MAP：头部双目做度量锚点，腕部相机做近场更新，物体账本做跨帧记忆，SSG 做步骤/恢复语义。

这比上一轮更接近评分结构：成功率是 binary，失败往往不是「这一步差 2 分」，而是「机器人不知道世界已经变了」。

## 3. 榜单头部方案的做法与瓶颈（在真实榜单缺失下的可检验分析）

### 3.1 先给结论：现在不能分析「真实榜首」

官方榜单未发布（[S10]）；占位 JSON 的 8 个模型是脚本生成的（[S11]）；runs 是 256/256 占位（[S12]）。因此任何「榜首用了什么」的说法都只能是**对公开基线族的推断**，不是对真实榜首的复盘。本轮把这一点写死，避免把占位数据当证据。

### 3.2 公开基线族的三种做法

| 族 | 代表 | 做法 | 强项 | 结构性弱点 |
|---|---|---|---|---|
| Unitree 官方底座 | WLA-1.0-Base（6B，2500h，64 任务，Apache-2.0）[S14] | 大规模真机预训练 + action expert + LoRA/全量微调 | G1 本体匹配、全量数据、工程成熟 | 仍是开环 imitation；对 human 撤销/遮挡没有显式状态 |
| 社区全量 LoRA | LingBot-VLA 2.0 UniBot LoRA（6.3B，33k，4090，10K steps）[S13] | Qwen3-VL + action expert + LoRA，joint 控制 | 单卡可复现、全量数据、成本低 | 只报开环 loss；无闭环恢复；腕部未标定 |
| 通用 VLA 迁移 | π0.5 / GR00T N1.5 系 | 通用预训练 + 任务微调 | 语义先验强、跨任务 | 腕部视角扰动敏感（WARP-VLA 39.2→78.3）[S16]；无 UniBot 专用几何 |

### 3.3 如果 <30% 是真的，瓶颈大概率在这五处

1. **终局放置/插入/闭合**：T27 的 30/30/40、T10 的 30/30/40 都把最后一步设成 success gate；最后一步失败，前面 60–70 分全白拿（[S7][S8]）。
2. **human 轴的「撤销」**：10 次里 2 次 human，占 20%；T27「叠了第二个之后拿下第二个」、T19「拉上拉链之后拉开」、T10「将插头拔起」都是**把已完成状态打回**（[S1][S7][S8]）。这不是靠更好的抓取能解的，必须有状态回滚/恢复。
3. **腕部视角/安装差异**：WARP-VLA 的 39.2→78.3 说明腕部扰动可以吃掉一半成功率（[S16]）；多机评测会放大这一点。
4. **遮挡后的物体状态丢失**：LIBERO-Occ 显示 SOTA VLA 在遮挡下显著退化（[S33]）；UniBot 的机器人手臂/夹爪本身就会遮挡目标。
5. **catastrophic task zeros**：32 个任务里只要有 5 个全零，就是 −15.6pp；公开基线族往往没有按任务做 triage。

### 3.4 头部方案「值得抄」和「不值得抄」的

- **值得抄**：全量 33k、6B 底座、LoRA/action expert、joint + EE 双空间的可切换、单卡可复现的工程。
- **不值得抄**：只盯开环 loss；把腕部当普通 RGB；用 SAM/DINO 等外部模型堆感知（单模型合规风险）；在 human 轴上只做数据增强、不做状态恢复；把步骤分当主目标。
- **最值得加**：一个**确定性的、外部的、可读的物体状态层**——它不增加第二个学习模型，却能把 P1/P3/P4/P6 和 human 撤销一起接住。

### 3.5 榜单观察协议（下一轮直接执行）

1. 拉 `leaderboard_data.json`，先看 `generated_from` 是否还是 `gen_leaderboard.py`；是则仍为占位；
2. 拉 `runs.html`，看是否还是 256/256 与「视频占位」；
3. 真实数据出现后，解析每任务成功率/步骤分/时长，生成 **task-zero 列表** 与 **step-success gap**；
4. 若 runs 有视频，按 P1–P6 做失败分类，优先看 top 3 的 T27/T10/T19/T24；
5. 用真实 p 重跑功效分析；如果 top <30%，确认「闭环状态/恢复」假设；如果 top 更高，重估本轮收益上限。

## 4. 本轮方案轮廓：WRIST-MAP

```text
语言(官方 160 条复述之一) → SSG 步骤图 → 当前步骤 s
                                      │
        ┌─────────────────────────────▼─────────────────────────────┐
        │ SAWC：头双目 3D 锚点 → 腕部 PnP → 手眼 T_E_C              │
```

## 1. 事实核对：本轮先把「三个灵感词」钉到官方约束上

### 1.1 评测与排名：成功率优先，步骤分只是 tie-break

官方任务页 [S3] 与中文手册 [S1]（英文版 [S2] 同义）明确：

- 通才模型必须完成 **32 个任务**；每个任务 **10 次独立运行**，覆盖 5 类泛化，每类 **2 次**。
- 单次真机执行最大 **180 秒**，超时记失败。
- 实时榜单按 **32 个任务的总平均成功率** 排序；成功率相同按 **总平均步骤分** 排序；仍相同则 **提交日期较早者** 靠前。
- 评测在 **N 台机器人** 上随机顺序执行；选手必须暴露 **N 个连续端口**（从 8765 开始），每个端口独立完成一个 episode；N 的确切值另行公布 [S4]。
- 观测只有 4 路 RGB（`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`）、双臂关节/EE 位姿、夹爪、`lower_body` 和语言；**没有深度、没有头部相机外参、没有 `state_d435`** [S4]。
- 动作必须返回 7 维 `action.pivot`；控制空间在 `joint` 与 `ee` 之间二选一 [S4]。

**排名公式**（把「总平均成功率」写成可计算形式）：

```text
S = (1/32) · Σ_{i=1}^{32} s_i
s_i = (1/10) · Σ_{a=1}^{5} Σ_{r=1}^{2} 1[success_{i,a,r}]

ranking key = (S, P, submit_date)
P = (1/32) · Σ_i step_score_i          # 具体聚合公式官方未逐字给出
```

这里最重要的修正是：**步骤分不是主 objective**。上一轮把「放置类步骤约占 59.7% 步骤分」当成主收益，本轮改为：放置/插入/闭合之所以重要，是因为它们决定 binary success；步骤分只用于 tie-break 和诊断。任何只提高部分步骤、不能把 episode 从 fail 变成 success 的模块，本轮都降权。

### 1.2 「榜首不到 30%」目前是占位数据，不是真实榜单

截至 **2026-10-25 10:42 UTC**：

- 官方 `leaderboard.html` 仍是 **Coming Soon** [S10]；
- `leaderboard_data.json` 的 `generated_from` 仍是 **`gen_leaderboard.py`**，是脚本生成的占位数据 [S11]；
- 占位 JSON 有 8 个模型、32 个任务；首位是 `MolmoAct2 / DexHacker`：成功率 **29.7%**、步骤分 **39.0**、平均时长 **44.02s** [S11]；
- `runs.html` 仍是 **256/256** 占位记录，详情页视频是占位 [S12]。

因此本轮不把「<30%」当事实，而把它当待验证假设：

- 若真实榜首确实 <30%，最可能的瓶颈不是模型容量，而是**闭环状态估计与恢复**；
- 若真实榜首高于 30%，说明公开基线族中被低估的工程/数据因素在起作用，WRIST-MAP 仍是增量，但收益上限要重估；
- 搜索中出现的 RoboChallenge Table 30 V2 43.33%（LoopWAM）是**另一个 benchmark**，不能拿来当 UniBot 上限 [S31]。

**榜单观察协议**（下一轮直接执行）：先检查 `generated_from` 是否仍为 `gen_leaderboard.py`；再检查 `runs.html` 是否仍为 256/256；真实数据出现后解析每任务成功率/步骤分/时长，生成 task-zero 列表与 step-success gap；若有视频，按失败分类看 T27/T10/T19/T24/T25。

### 1.3 `action.pivot` 存在，但演示是「固定底座 + 少量姿态变化」

提交接口要求每个 chunk 返回 `action.pivot [7]`；数据集字段名为：

```text
[vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]
```

`pivot_3/4/5` 的官方语义未在已读手册中解释，不能把它们直接当作 waist 三轴。本轮抽样了 8 个任务、每个 200 帧（HangCup、ConveyorSorting、StackBowls、OrganizeBookshelf、PackBag、FoldTowel、OrganizePencilCase、PlugCharger）[S6]：

- `vx / vy / angle_z` 全部为 **0**；
- 多数任务 `height = 0.74`、`pivot_4 = 0.15`；
- 只有 **FoldTowel** 的 `height` 在 **0.7116–0.74** 之间变化，且 `pivot_4 = 0`；
- `pivot_3 / pivot_5` 在所有抽样中为 0。

结论要精确：**在这 8 个任务里，底盘平移/旋转是 OOD；高度/躯干姿态在 FoldTowel 里有演示，属于部分分布内**。因此「步态规划」在 UniBot 桌面任务里不是可直接端到端学习的动作，而是：

1. **姿态优先**：`height` 与 `pivot_4`（疑似躯干/腰部，语义待探针）是安全、连续、部分在分布内的主动视角自由度；
2. **底盘最后**：`vx/vy/angle_z` 只在目标不可达、遮挡严重、且调试槽证明评测器真的执行 pivot 时才用；
3. **不做足端规划**：API 只给 base command，底层步态由控制器负责；在策略侧做 footstep RL 既 OOD 又浪费 180s。

### 1.4 腕部相机有内参、没有外参；头部双目才是度量锚点

数据集 `camera_params` [S6] 给出：

| 项 | 数值/结论 |
|---|---|
| 头部双目 | 已矫正；基线 `T = [-58.25, -0.17, 0.58]` mm，基线幅值 **58.25mm**；左右内参与畸变齐全；`fx≈282` |
| 腕部彩色 | 左右内参 `fx≈436.4 / 435.1`，畸变模型 `inverse_brown_conrady`；640×480 |
| 腕部 IR | 有左/右 IR 内参与 IR-to-color 外参；评测 API 不提供 IR 图 |
| 腕部外参 | **没有腕部相机到 EE/base 的外参** |
| 深度 | 四路 RGB 均无深度；`state_d435` 在数据里有，但不在提交观测目录 |
| 头部姿态 | 一个 episode 内并非完全固定：HangCup 抽样中 `state_d435` 的 x 变化约 **1.9cm**、z 约 **0.5cm**、pitch 约 **2.6°**，与腰部姿态相关 |

这两条事实决定了本轮的技术入口：**腕部是一台没有标定的近场单目相机；头部双目是唯一有度量基线的外部传感器；线上头部姿态必须用 `lower_body` 腰部关节 + 离线拟合恢复，不能假设恒定。**

### 1.5 公开基线族的真实形态：6B + 全量 33k + LoRA，开环指标好，闭环未知

公开可查的 UniBot LoRA 方案 [S13]：

- **LingBot-VLA 2.0**：6.3B（Qwen3-VL-4B + Qwen2 action expert + MoE），LoRA rank **64**/alpha **32**，只训 q/v/o，约 65M 可训练参数；
- 全量 **32 任务 / 33,276 episodes**，10K steps，单卡 **RTX 4090**，bf16；
- joint 控制（arms 14、grippers 2、waist 4、base 3 的 canonical 空间）；
- 只报开环 `val/loss 0.085` 与 ArrangePlates 的 MSE **0.229** / MAE **0.176**，**没有闭环成功率**；
- 50-step chunk 在 4090 上约 **0.35s**。

另一条公开底座是 Unitree **WLA-1.0-Base**：6B、2,500 小时、64 任务、Apache-2.0、24GB 可微调 [S14]。

这类方案的代表性很强：**算力不是门槛，全量数据 + 6B 底座 + LoRA 已经是公开可复现的基线**。它最可能的瓶颈不是「模型不够大」，而是：

1. 开环 loss 与闭环 success 脱节；
2. 没有显式物体状态，遮挡/人为移动后只能重新 grounding；
3. 腕部相机被当普通 RGB，没有度量标定；
4. 没有恢复策略，human 轴「撤销」直接把已完成的步骤打回；
5. 32 任务里少数 catastrophic zeros 拉低总平均。

这五条正好对应 WRIST-MAP 的五个切入点。

## 2. 评分算术：为什么先做状态层，而不是先做更大的模型

### 2.1 成功率与步骤分是两套目标

```text
success  = episode 是否在 180s 内完成官方终局判定
step     = 官方 score_steps 的加权完成度
rank     = 先比 success 均值，再比 step 均值，再比提交日期
```

按上一轮抓取的 32 个 `info.json` 汇总：终局步骤合计 **1275/3200 = 39.8%**；放置/插入/堆叠/闭合类步骤合计约 **1910/3200 = 59.7%**（关键词粗分类）。这组数字仍然有用，但只能这样用：

- 终局步骤是 **binary success 的最后一道门**（本报告按此建模，官方逐字判定未公开）；
- 步骤分用于 **定位钱丢在哪一步**，不是训练主 reward；
- 任何「只把 60 分提到 70 分、但没有越过终局」的优化，在排名上可能毫无收益。

### 2.2 320 次评测的统计量

| 量 | 数值 | 含义 |
|---|---:|---|
| 总评测次数 | 32 × 10 = **320** | 成功率的样本量 |
| 单任务权重 | 1/32 = **3.125pp** | 一个任务从 0% 到 100%，总分 +3.125pp |
| 单泛化轴权重 | 2/10 = **20%** | 某一轴全线失败，最多损失 20pp |
| 总体成功率标准误（p≈0.3） | **≈2.56pp** | 320 trials 的近似 SE |
| 95% 置信区间（p≈0.3） | **≈±5.0pp** | 所以 +3pp 单独看接近噪声 |
| 一个任务 catastrophic zero | **−3.125pp** | 5 个任务全零，直接 −15.6pp |
| human 轴子集 | **64 trials** | p≈0.3 时 SE≈5.7pp；+15pp 才比较稳 |

因此本轮的预算逻辑是：**先消除 catastrophic zeros，再攻跨轴终局能力，最后才做 steps 微调**。主目标定 **+5pp**，而不是 +3pp；如果只能拿到 +3pp，必须用配对任务×轴分析或更多 trials 才能说服自己不是噪声。

### 2.3 一个更锋利的失败模型：P1/P3/P4/P6 其实是同一个状态问题

上一轮 PILOT 的失败模式：

- P1：落点 grounding 错；
- P3：姿态不对；
- P4：释放过早；
- P6：不验证就以为完成。

本轮把它们统一成：

```text
P1/P3/P4/P6 的本质不是「当前帧没看清」，
而是「机器人没有维护一个跨帧的物体/容器状态」。

- 人把碗移走 → 状态没更新 → 还往旧位置放（P1）
- 自己手臂挡住目标 → 状态丢了 → 重新猜（P1/P6）
- 放置后物体弹跳/滚动 → 没有 settle 状态 → 以为完成（P4/P6）
- 已叠好的碗被拿走 → 步骤状态没回滚 → 继续叠第三个（P3）
- 人把底座挪了 → base 系下所有物体一起动 → 误判成物体各自移动（P1）
- 自遮挡/人遮挡使当前帧看不到目标 → 没有状态预测 → 重新猜（P1/P6；LIBERO-Occ 显示 SOTA VLA 在遮挡下显著退化 [S33]）
```

于是主判断是：

> **把 PILOT 的「单帧目标 → 动作」改成「单帧观测 → 状态更新 → 目标 → 动作」。**
> 状态层就是 WRIST-MAP：头部双目做度量锚点，腕部相机做近场更新，物体账本做跨帧记忆，SSG 做步骤/恢复语义。

这比「再训一个更大的 VLA」更贴近评分结构：成功率是 binary，失败往往不是「这一步差 2 分」，而是「机器人不知道世界已经变了」。

### 2.4 预算分配（修订上一轮）

```text
状态层（SAWC + TAOM + WVC）           35%
恢复与验证（SSG + NRB + SVL + TZT）   25%
VLA 与 map token / overlay             15%
主动感知与调试（BAP + DebugLoop）      10%
数据/工程/合规                         15%
```

如果算力或调试槽受限，先走 **推理增强最小版**：不重训 VLA，只加 SAWC 标定、TAOM overlay、PGL/OPT、SVL、SSG；这版能验证「状态层是否本身有增益」，再决定是否训练 map token。

## 3. WRIST-MAP 架构

### 3.1 总览

```text
                        官方语言（160 条复述之一）
                                  │
                                  ▼
                    SSG：任务→官方步骤图→当前步 s_t
                                  │
      ┌───────────────────────────┴───────────────────────────┐
      │                                                       │
      ▼                                                       ▼
  头双目 RGB                                          腕部 RGB + EE 位姿
      │                                                       │
      ├─► 立体匹配/三角化 ──► 3D 点（base 系）                 ├─► 去畸变/WVC
      │        │                                              │
      │        ▼                                              ▼
      │   SAWC：PnP + 手眼 AX=XB ──► T_E_W（在线 refine）   目标 2D/可见性
      │        │                                              │
      │        └──────────────┬───────────────────────────────┘
      │                       ▼
      │              TAOM：物体/容器位姿账本
      │              （节点、协方差、存在性、变化检测、
      │                底座整体位移补偿、步骤回滚触发）
      │                       │
      │          ┌────────────┼─────────────┐
      │          ▼            ▼             ▼
      │      PGL 锚点     OPT 释放位姿    map token/overlay
      │          └────────────┼─────────────┘
      │                       ▼
      └──────────────► GPR-VLA（唯一学习模型）
                              │
                              ▼
                    action chunk（joint / ee）
                              │
                              ▼
                    SVL：腕部伺服→缓放→稳定性/谓词校验
                              │
                 ┌────────────┴────────────┐
                 ▼                         ▼
          NRB/SSG 恢复                  BAP 条件触发
          （撤销/移走/回滚）       （waist/height 优先，底盘最后）
```

设计原则：

1. **测量，而不是更多视角**：腕部不是第三只眼，而是一台没有标定的近场单目相机；头双目提供米制锚点。
2. **状态外置**：物体账本、步骤图、手眼标定都是可读、可调试、可关闭的确定性模块；唯一学习模型仍是 VLA。
3. **每个组件有 fallback**：标定失败→2D 锚点；地图失败→腕部伺服；BAP 失败→关闭；SSG 不确定→保守重试。
4. **先姿态后底盘**：`height`/waist 优先，`vx/vy/angle_z` 只在探针验证后使用。
5. **不把步骤分当 reward**：步骤图用于诊断、恢复和 success 门控，不用于刷部分分。

### 3.2 坐标与记号

所有变换 `T_A_B` 表示「把 B 系坐标映射到 A 系」的 4×4 齐次变换；`inv(·)` 为逆，`·` 为矩阵乘。

| 记号 | 含义 | 来源 |
|---|---|---|
| `B` | 机器人 base 系 | API EE 位姿的坐标框架 |
| `T` | torso/腰部系 | 数据集 `state_torso`；线上由 `lower_body` 恢复 |
| `H` | 头部左相机系 | 数据集 `state_d435`；线上由 `T_B_T · T_T_H` 恢复 |
| `W` | 腕部相机系（左/右） | 数据集内参；无外参 |
| `E` | 夹爪/EE 系 | API `*_ee_pose_gripper_base` |
| `O` | 物体系 | TAOM 节点 |
| `C` | 容器/目标系 | TAOM 节点；由容器点云/关键点拟合 |
| `G` | 释放时刻的 EE 系 | 演示中的终局位姿 |

核心关系：

```text
T_B_W = T_B_E · T_E_W                     # 腕部相机在 base 系
T_B_H = T_B_T · T_T_H                     # 头部相机在 base 系
T_B_O = T_B_C · T_C_O                     # 物体相对容器
T_B_G = T_B_C · H̄                         # OPT 的释放位姿
```

其中 `T_E_W` 是 SAWC 要求的手眼变换；`H̄` 是容器系下的释放位姿统计。

### 3.3 SAWC：头双目锚定的腕部自标定

#### 3.3.1 为什么不能用「标定板 + 固定外参」

- 评测是远程 API，选手无法保证每台机器人、每次安装的腕部相机外参一致；
- 数据集没有腕部到 EE/base 的外参 [S6]；
- 在腕部视角扰动设置下，π0.5 只有 **39.2%**，WARP-VLA 提升到 **78.3%** [S16]；
- 但腕部有内参、有近场细节；头双目有 58.25mm 基线和已矫正图像，是天然的米制锚点 [S6]。

所以 SAWC 的目标不是「标定一次永久使用」，而是：**在每条 episode 的自然操作中，用头部双目和腕部图像的共同观测，在线估计并 refine `T_E_W`。** 这条路线借用了无标定手眼/3D 标定的成熟几何 [S30]，但把「标定板」换成了场景中自然可见的目标。

#### 3.3.2 头部位姿的线上恢复

线上 API 不提供 `state_d435`，只提供 `lower_body`（15 维，含 waist yaw/roll/pitch）[S4]。恢复分两步：

1. **离线拟合 `T_T_H`**：用数据集里的 `state_torso`、`state_d435`，对每一帧计算 `T_T_H = inv(T_B_T) · T_B_H`；取鲁棒中位数。若头部相对 torso 有额外俯仰，则把残差拟合成 waist 角度的低阶多项式。
2. **线上恢复 `T_B_T`**：用 `lower_body` 的 waist 三轴 + 腿部关节（或 height）与数据集 `state_torso` 拟合一个低阶（二次）多项式或查表；残差用 EKF 平滑。然后 `T_B_H = T_B_T · T_T_H`。

这不是第二个学习模型：它是离线标定表/低阶回归，权重只有几十个数，随模型卡披露。若拟合残差在留出集上 >1cm/1°，则退回常数 `T_B_H`，并降低 TAOM 的度量置信度。

#### 3.3.3 离线/在线标定流程

**输入**：头左/右 rectified RGB、腕部 RGB、`T_B_E`、`T_B_H`（恢复值）、各自内参/畸变。

**步骤**：

1. **去畸变**：头双目已 rectified；腕部按 `inverse_brown_conrady` 反解畸变（用数据集声明的模型，数值验证重投影）。保留原始像素坐标用于 PnP。
2. **共同观测**：只选头部与腕部同时看到同一目标、且手臂低速（EE 线速度 <0.1m/s）的帧。优先选抓取前 0.5–1.5s 的接近段；此时目标在腕部近场、在头部中距离。
3. **头部 3D 点**：
   - 在头左图提取 ORB/SIFT 特征，或在训练/离线阶段由 VLA 关键点头给出目标/容器关键点；
   - 在头右图做极线约束匹配；三角化得到 `P_H`；
   - 变换到 base：`P_B = T_B_H · P_H`；
   - 只保留桌面 ROI、重投影误差 <1.5px、深度 0.25–1.2m 的点。
4. **腕部 2D 对应**：
   - 首选：VLA 关键点头在腕部图输出同一语义关键点（目标中心、容器角点、把手/插头端点）；
   - 备选：ORB/SIFT 描述子 + 最近邻 + RANSAC；不同视角下描述子匹配较弱，必须用几何一致性过滤；
   - 至少 8 个对应点，空间分布覆盖图像 ≥40% 区域。
5. **PnP**：`cv2.solvePnPRansac`（EPnP 初值 + LM refine），得到 `T_B_W`；内点重投影 RMSE 必须 <5px。
6. **手眼**：`T_E_W = inv(T_B_E) · T_B_W`。
7. **多帧鲁棒聚合**：对 K 帧（K≥8）的 `T_E_W` 取平移中位数、旋转四元数弦均值；用 MAD 剔除离群帧；若平移 MAD >5mm 或旋转 MAD >1°，判定标定不稳定。
8. **运动一致性检查（AX=XB）**：线上用腕部单目光流/视觉里程计估计 `T_W1_W2`（离线可用腕部 IR 双目做校验），用 EE 位姿得到 `T_E1_E2`，检查
   ```text
   T_E1_E2 · T_E_W ≈ T_E_W · T_W1_W2
   ```
   残差 >1cm/2° 的帧丢弃。
9. **在线 refine**：以离线/首帧 `T_E_W` 为先验，EKF 状态为 6DoF；过程噪声 0.2mm/0.05° 每帧；仅在 >10 个内点、RMSE <5px、手臂低速时更新；接触/夹持阶段冻结。
10. **留出验证**：用未参与标定的帧，把 TAOM 的 3D 点投影到腕部图；重投影 RMSE <5px 才算通过。

#### 3.3.4 误差预算

头部双目 `fx≈282`、基线 `b=0.05825m`。深度 `Z` 的误差近似：

```text
σ_Z ≈ Z² / (fx · b) · σ_d
```

取视差误差 `σ_d=0.2px`：

| 头部深度 Z | 视差 | σ_Z（0.2px） | 横向 σ（0.5px） |
|---:|---:|---:|---:|
| 0.4m | ≈41px | ≈1.9mm | ≈0.7mm |
| 0.6m | ≈27px | ≈4.4mm | ≈1.1mm |
| 1.0m | ≈16px | ≈12.2mm | ≈1.8mm |

腕部 `fx≈436`，在 10cm 处 0.5px 横向误差约 **0.11mm**，但单目没有深度。因此：

- 头部负责 **全局、米制、厘米级**；
- 腕部负责 **近场、亚厘米级**；
- TAOM 负责把两者接起来，并在时间上维持状态。

这也解释了为什么「只用头双目」不够：1m 处 ~12mm 的深度误差对插头/叠碗的终局容差可能太大；「只用腕部」也不够：单目无深度、无全局位姿、遮挡即丢。

#### 3.3.5 fallback

| 失败 | 处理 |
|---|---|
| 头腕无共同观测 | 用数据集平均 `T_E_W` 作先验；只开 TAOM 的 2D 锚点，不开 6D |
| 头部位姿恢复失败 | `T_B_H` 用常数；降低地图置信度；优先腕部相对伺服 |
| PnP 内点 <8 或 RMSE >5px | 丢弃该帧；连续 3 帧失败→关 SAWC |
| 手眼漂移 >1cm/2° | 关度量地图，保留身份账本/2D overlay |
| 透明/反光/无纹理 | 不做 PnP；用 2D 关键点 + 相对深度 |

### 3.4 TAOM：桌面物体位姿账本

#### 3.4.1 为什么是「物体账本」而不是「全 SLAM」

桌面任务的场景很小：一张桌子、10 个左右物体、base 固定或偶尔被人挪动；没有长距离回环，没有整屋建图需求。全 SLAM 会带来：

- 稠密地图/关键帧的内存与延迟；
- 动态物体（人手、抹布、传送带）污染地图；
- 需要外部视觉模型，增加单模型审计风险；
- 与 180s episode、30Hz 控制不匹配。

TAOM 只保留**物体级节点**：

```text
M_t = { O_i : (p_i, q_i, Σ_i, e_i, v_i, s_i, t_i) }
```

外部证据也支持「显式状态层」而不是更大的端到端策略：Ledger 把长期物体记忆外置，RoboMME 上 **64.3% vs 45.9%**，object permanence **86.7% vs 56.2%** [S18]；OASIS-Map 的 object-level change detection 在 car replacement 上 F1 **0.783**、3RScan moved object association F1 **0.667** [S19]；DAF object SLAM 专门处理「测量与 landmark 关联错」[S20]；LLM-Enhanced Object SLAM 用物体尺寸/朝向先验在稀疏观测下把 mapping accuracy 提升 **36.8%** [S21]；EchoVLA 的 scene memory + episodic memory 在移动操作上比 π0.5 高 **+0.20/+0.11** [S22]。

| 字段 | 含义 |
|---|---|
| `p_i, q_i` | base 系位置/姿态（刚体） |
| `Σ_i` | 6×6 位姿协方差 |
| `e_i` | 存在概率（log-odds） |
| `v_i` | 可见性/置信度 |
| `s_i` | 语义状态：free / grasped / placed / inside / open / closed / zipped |
| `t_i` | 最近观测时间 |

容器/桌面作为特殊节点：容器提供 `C` 系；桌面提供支撑平面先验。

#### 3.4.2 观测前端：只用同一 checkpoint 的辅助头 + 几何

为了满足「通才单模型」和审计要求，TAOM 在推理期**不引入 SAM/DINO/FoundationPose 等第二个学习模型**。观测来自三处：

1. **VLA 辅助头**（与动作头共享 backbone，同一 checkpoint）：
   - 目标/容器关键点热图（头左、头右、腕部）；
   - 可见性/存在性 logits；
   - 步骤谓词 logits；
   - 可选的物体中心/方向回归。
2. **头双目几何**：
   - 用辅助关键点或 ORB 特征做左右匹配、三角化；
   - 桌面 ROI 内点云去平面、聚类；对刚体拟合长方体/圆柱，得到容器轴与包围盒；
   - 协方差由视差/像素噪声传播。
3. **本体/接触**：
   - 夹爪闭合 + EE 运动 → 物体被夹持；
   - 抓取前记录 `T_E_O`（物体相对 EE 的抓取偏移），夹持期间 `T_B_O = T_B_E · T_E_O`；
   - 释放后物体转为 static，位置由腕部/头部观测更新。

离线标签可以用 SAM/6D 位姿模型生成，但**这些权重不进入推理**；模型卡中明确写出「仅离线标注」。

#### 3.4.3 数据关联

对每个观测 `z_j` 与已有节点 `O_i` 计算代价：

```text
c_ij = Mahalanobis(z_j, O_i; Σ_i)
     + λ_color · d_color
     + λ_size  · d_size
     + λ_step  · d_step
```

- 颜色用 Lab 直方图/主色，不用学习模型；
- 尺寸用包围盒/关键点距离；
- `d_step` 来自 SSG：当前步骤期望操作哪个物体/容器；
- 用匈牙利算法做全局匹配；卡方 95% 门限外的观测新建节点；
- 对相同碗/杯/积木，若两个假设代价接近，**保留多峰**，等下一次观测或步骤事件消歧；不允许静默合并。

#### 3.4.4 状态更新与位姿图

对每个节点做 EKF/鲁棒最小二乘：

```text
预测：x⁻ = x⁺（静态物体）；Σ⁻ = Σ⁺ + Q
更新：K = Σ⁻ Hᵀ (H Σ⁻ Hᵀ + R)⁻¹
      x⁺ = x⁻ + K (z − h(x⁻))
      Σ⁺ = (I − K H) Σ⁻
```

每 0.2s 或检测到变化时，解一个小型位姿图：

- 节点：物体/容器/桌面；
- 因子：静态先验、视觉观测、夹持约束、支撑/containment、步骤谓词；
- 鲁棒核：Huber；10–20 个节点，Gauss-Newton 2–3 次，目标 <5ms。

#### 3.4.5 变化检测：把「人动了世界」分类

对每个节点计算新息 `r = z − h(x⁻)` 与归一化平方 `rᵀS⁻¹r`。超过卡方阈值时，分类：

| 模式 | 判据 | 处理 |
|---|---|---|
| **底座整体位移** | ≥3 个静态物体同时同向移动，且相对位置不变 | 估计 `ΔT_B`，把所有节点变换到新 base 系；不因底座移动本身回滚步骤 |
| **物体局部移动** | 只有 1–2 个节点新息大，其他稳定 | 更新该节点；若谓词失效→SSG 回滚/重试 |
| **物体消失** | 观测缺失 + 存在概率下降 | 标记 missing；若是被拿走→重新规划；若只是遮挡→保持预测 |
| **状态变化** | 外观/几何变化（开/合、拉链、叠放） | 更新 `s_i`；触发谓词复核 |
| **人手/抹布** | 动态、无稳定刚体拟合 | 不作为地图节点；作为遮挡处理 |

**底座整体位移**是这轮新增的关键细节：T11 的「抓取电池之前动底座」、T25 的「放了第一个马上放第二个挪一下底座」都说明人可能直接挪机器人。若把整体位移误判成每个物体各自移动，TAOM 会把地图弄乱。用「静态物体一致性」估计 `ΔT_B`，是比 base 里程计更可用的信号。

#### 3.4.6 输出给 VLA

两种互补表示：

1. **2D overlay**（默认，安全）：把目标/容器位姿、抓取点、释放点、协方差椭圆投影到头/腕图像，画十字/朝向/容差圈；训练与推理用同一渲染器，避免域差。
2. **map token**（可选，需训练）：每个物体编码为
   ```text
   [p_rel, q_rel(6D), log σ, existence, semantic_id, relation]
   ```
   经一个小 MLP（属于同一 checkpoint）变成 4–8 个 token，最多 10 个物体；总 token 控制在 40–80。训练时做 20% map dropout，防止模型过度依赖地图。

#### 3.4.7 fallback 与适用范围

| 场景 | 策略 |
|---|---|
| 刚体、不透明、桌面 | 全量 6D + 协方差 |
| 透明/反光 | 只保留 2D 锚点 + 存在性；不做 6D |
| 布料/拉链/绳 | 只做区域/端点关键点；交给 VLA + SVL |
| 地图置信度低 | 冻结地图，退回腕部伺服 + 原始 VLA |
| 多物体同名 | 保留多峰，步骤先验消歧；必要时重观测 |

### 3.5 WVC：腕部视角规范化

腕部相机的价值在近场，但它的视角随手臂运动剧烈变化，且不同机器人安装差异大。WVC 做三件事：

1. **去畸变**：按 `inverse_brown_conrady` 反解；保留原始像素用于 PnP。
2. **地图条件裁剪/缩放**：
   - 若 TAOM 给出目标深度 `z`，按 `s = fx · W_m / z` 裁剪固定米制窗口（例如 15–25cm），再 resize 到 224/256；
   - 若深度未知，用物体尺寸先验或原始全图；
   - 裁剪中心由目标/容器投影决定，而不是固定图像中心。
3. **方向规范化 + 夹爪 mask**：
   - 用 torso/EE 重力方向构造虚拟相机旋转 `R_align`，用单应 `K R_align K⁻¹` 把图像转正；同时更新内参；
   - 用 G1/Dex1 的夹爪网格 + `T_E_W` 渲染 mask；没有网格时用标定得到的固定多边形；
   - mask 成灰色/黑色，减少「夹爪外观」对策略的 shortcut（Cloak 的证据：mask 腕部夹爪区域反而提升跨 embodiment 迁移 [S25]）。

**训练增强**（直接对应 WARP-VLA 的扰动）：

- 随机腕部外参扰动：平移 ±1–2cm、旋转 ±3–5°；
- 随机裁剪/缩放/方向 ±10°；
- 随机遮挡 10–30%；
- 随机夹爪 mask 形状/边缘。

**推理策略**：

- 默认只做 **overlay + 去畸变**，不动裁剪，风险最低；
- 只有 TAOM 置信度高时，才启用 canonical crop；
- 若 canonical crop 在调试槽无增益，关闭，回到 raw wrist + overlay。

WVC 本身不是学习模型；它是确定性图像变换。它的作用是让 VLA 看到的腕部图像更接近「同一台相机、同一尺度、同一方向」，从而减少跨机安装差异。

### 3.6 SSG + NRB：步骤图、撤销与恢复

#### 3.6.1 步骤图

从 `tasks_v2/<slug>/info.json` 的 `score_steps` 构建每任务线性图：

```text
s0 → s1 → … → s_k
```

每个节点包含：官方步骤文本、权重、期望物体/容器、完成谓词、可撤销标志。语言匹配：

- 先精确匹配 32×5=160 条英文复述（数据集 `tasks.parquet` 的 `@` 分隔）[S5]；
- 再规范化（小写、去标点、数字/颜色同义词）；
- 最后用离线句向量做兜底；阈值以下不猜任务，直接走保守 VLA。

#### 3.6.2 谓词与状态机

谓词不是「模型说完成」，而是多源证据：

```text
done_i = sigmoid(w1·VLA_step_logit
               + w2·TAOM_relation
               + w3·gripper_event
               + w4·stability)
```

具体谓词由步骤文本 + 演示事件定义；阈值用演示分布校准。典型：

- 抓取：夹爪闭合 + 物体随 EE 运动；
- 放置：物体在容器支撑面内 + 相对位姿稳定 0.5s；
- 插入：插头端点进入插座容差 + 无回弹；
- 闭合：拉链/盒盖状态从 open→closed；
- 叠放：上物体支撑在下物体上 + 位姿稳定。

状态机规则：

```text
若 done_i 稳定为真（连续 N 帧）→ s_t ← s_{i+1}
若 done_i 从真变假（且不是遮挡）→ s_t ← s_i，触发恢复
若物体 missing/被移走 → 重定位或回退到依赖该物体的步骤
若底座整体位移 → 只更新地图，不自动回滚步骤
```

**抗遮挡**：谓词从真变假时，先看 TAOM 存在概率与可见性；只有「物体确实不在/状态确实变了」才回滚，避免手臂遮挡造成假撤销。

#### 3.6.3 步骤分只做诊断

SSG 记录每任务每步的完成率、首次完成时间、回滚次数。这些指标用于：

- 找 catastrophic zeros；
- 分配调试槽；
- 判断是「没到终局」还是「到了终局但释放失败」。

它不作为训练 reward，也不为了 +部分分而牺牲 success。

#### 3.6.4 NRB：官方备注的破坏→恢复对

NRB 用公开 human 备注构造训练对（只在训练数据，不进推理）：

| 任务 | 官方备注 | 破坏 | 恢复目标 |
|---|---|---|---|
| T27 | 叠了第二个之后拿下第二个 | 移除 bowl2 | 重新放 bowl2 → 继续 bowl3 |
| T19 | 拉上拉链之后拉开 | 拉开拉链 | 重新拉合 |
| T14 | 拧开盖子之后拧动回来 | 盖回瓶盖 | 再拧开 → 倒药 |
| T17 | 笔盒合上之后手动打开 | 打开盒盖 | 重新合上（终局） |
| T24 | 可乐快到了然后放回传送带起点 | 目标远离 | 重新抓取→放置 |
| T10 | 将插头拔起 | 拔出插头 | 重新抓取→插入 |
| T12 | 中途把锁拿走 | 锁被移走 | 重新定位锁→继续翻环 |
| T11/T25 | 动底座/挪底座 | base 整体位移 | 重新锚定地图→继续当前步 |

这些备注大概率就是 human 轴的真实剧本（编号含义未核实）；即使不是，也是分布内的高价值扰动。NRB 的目标不是「记住剧本」，而是让模型学会**状态被撤销后如何重新观察、回滚、重试**。
### 3.7 PGL + OPT：从「语言坐标」到「容器系释放位姿」

#### 3.7.1 PGL 三级目标

PGL 不改官方指令，只把「放哪里」逐级显式化：

1. **槽位/区域（语义级）**：SSG 从官方步骤文本得到目标容器/区域（如「onto the plate with the matching color」「into the rack」）；TAOM 给出候选容器节点与相对关系。
2. **2D 锚点（视觉级）**：把候选 6D 目标投影到头/腕图像，渲染十字、朝向、容差圈；训练时用演示真实目标做同一渲染，保证训练/推理同分布。
3. **6D 位姿（度量级）**：由 OPT 的容器系释放位姿统计给出 `T_B_G`，送入 VLA 条件或 SVL 伺服。

三级中任何一级失败都可以降级：6D 不可信→2D 锚点；2D 不可信→槽位语义 + VLA 原行为。

#### 3.7.2 OPT 的离线统计

对任务 `t` 的每条演示 `i`：

1. 用 TAOM/离线标注估计容器系 `T_B_C_i`；
2. 取释放时刻 `t_i^rel` 的 EE 位姿 `T_B_G_i`；
3. 计算容器系释放位姿：

```text
H_i = inv(T_B_C_i) · T_B_G_i
```

对所有演示的 `H_i`：

```text
平移：H̄_p = median_i(H_i.p)
旋转：H̄_q = chordal_mean_i(H_i.q)       # 四元数弦均值，再归一化
离散度：σ_p = std_i(H_i.p)
        σ_θ = angle_spread_i(H_i.q)
容差：τ_task = 95th_percentile_i(||H_i.p − H̄_p||)
```

#### 3.7.3 线上迁移与不确定性

线上 TAOM 给出 `T̂_B_C` 与协方差 `Σ_C`；则：

```text
T̂_B_G = T̂_B_C · H̄
Σ_G = J_C Σ_C J_Cᵀ + Σ_H
```

其中 `Σ_H` 是演示离散度（不是模型 aleatoric 不确定性）。决策规则：

```text
若 trace(Σ_G) 小且 σ_θ 小        → 直接执行 H̄（快）
若中等                           → 慢速 + 腕部视觉伺服到投影锚点
若大                             → 放弃 6D，只用 2D 锚点 + 保守放置
若容器是透明/布料/不可拟合        → 不进 OPT，走 2D/SVL
```

**为什么是「少样本」**：迁移的是 K 条演示的**容器系相对位姿统计**，不是动作轨迹复制；零梯度、可缓存、跨外观/背景/位置。K 可取 1–4（同任务、同步骤、行为对齐的演示），离散度直接决定控制风格。

#### 3.7.4 容器系估计

- 刚体容器：头双目点云 + 平面/长方体/圆柱拟合，得到容器轴与中心；协方差由点云传播。
- 未见容器：用关键点/包围盒 + 桌面支撑面构造局部系；方向取最长轴/开口方向，若歧义则保留多峰。
- 透明/反光：不拟合 6D，只给 2D 区域/开口中心。
- 容器被人移动：TAOM 变化检测更新 `T_B_C`，OPT 目标随之更新；这是 human 轴的关键。

### 3.8 SVL：落点 settle-verify 闭环

终局步骤是 success 门控，释放失败（掉落、弹跳、未到位、未闭合）不能靠「放完就完」发现。SVL 把释放当成一个需要验证与修复的阶段。

```python
def place_and_verify(step, obs, plan, budget=2):
    for attempt in range(budget + 1):
        anchor = PGL.render(plan, obs, taom)
        ctx = {
            "step": step,
            "map": taom.tokens_or_overlay(),
            "anchor": anchor,
        }
        for chunk in stream(policy.act(obs, ctx)):
            send(chunk)
            if predicate_met(step, obs, taom):
                break

        if not predicate_met(step, obs, taom):
            plan = revise(plan, obs, taom, reason=diagnose(step, obs, taom))
            continue

        open_gripper(slow=True)
        wait(0.5)
        taom.update_after_release(step, obs)

        if stable(step, obs, taom, window=0.5):
            return True

        if repairable(step, obs, taom):
            plan = nudge_plan(step, obs, taom)
        else:
            plan = regrasp_plan(step, obs, taom)
    return False
```

关键判据：

- `predicate_met`：SSG 谓词头 + TAOM 关系 + 夹爪事件；不是单帧分类。
- `stable`：释放后 0.5s 内物体相对容器/支撑面的位移 < `ε_rel`，且谓词保持；`ε_rel` 由演示统计给出（叠碗大、插头小）。
- `nudge`：轻推/旋转/下压的短动作；只在物体仍可触及且未掉落时用。
- `regrasp`：重新抓取；预算内优先于长距离重试。
- `budget`：普通任务 ≤2 次；长程/闭合任务（T16/T17/T31）≤1 次；总时长由 Endurance Governor 兜底。

SVL 与 TAOM 的交互：

- 释放后物体若滚动/弹跳，TAOM 更新位姿；若超出容器容差，SVL 触发 nudge/regrasp。
- 若人把物体拿走，TAOM 标记 missing，SVL 不再盲目重放，而是回到 SSG 重规划。
- 若底座被挪动，TAOM 先做整体位移补偿，再判断落点。

### 3.9 BAP：姿态优先、底盘最后的主动感知

#### 3.9.1 证据与边界

- SaPaVe：固定相机 36.17% → 固定+腕部 52.33% → 主动相机+腕部 **73.16%**；真机 π0 45.0%、GR00T-N1 53.75%、其方法 85.0% [S15]。改变视角本身有独立增益。
- ActiveAlign：朴素地先动相机再交给未对齐的 VLA，会把 LIBERO 的 46.3% 打到 **11.5%**；用 post-move 状态对齐训练后可到 70.7%/72.7%，真机遮挡 35/90→83/90 [S17]。**动视角会造成分布漂移，必须对齐。**
- ActivePose：腕部主动 6D 位姿估计 + next-best-view 消歧 [S24]；ActiveVLA 也把主动视角作为 VLA 的显式动作维度 [S23]。
- B*：固定底座机械臂把 base 当额外 3 DoF 做最优放置 [S28]。
- STRIDER/ULC/Reachability：多步态 loco-manipulation 很强，但 UniBot 的演示里 base 平移/旋转为 0，API 只给 base command，底层步态不可控 [S26][S27][S29]。

因此 BAP 的边界是：

```text
先 waist/height（部分在分布内）
再小步底盘（OOD，需探针）
不做足端规划/步态 RL
```

#### 3.9.2 pivot 语义探针

`pivot_3/4/5` 的语义未核实，不能直接当 waist 三轴。DebugLoop 先做**不计分单任务探针**（官方提供单任务测试通道 [S32]）：

1. 在安全场景中，一次只改一个 pivot 通道（小幅度、限速）；
2. 记录头部图像变化、EE 位姿、`lower_body`、是否触发保护；
3. 拟合「pivot 通道 → 实际关节/底座运动」的映射；
4. 若某通道无可见效果或导致不可恢复运动，标记禁用；
5. 只有通过探针的通道才允许在计分跑中使用。

探针不通过→BAP 关闭，回到纯 VLA + SVL。

#### 3.9.3 有限状态控制

```text
状态：
  NORMAL       目标可见、TAOM 置信度高 → 不做 BAP
  LOW_VIS      目标可见性低 >0.5s → 调 waist/height（演示范围内）
  OUT_OF_VIEW  目标不在视野/工作空间 → 小步底盘（仅探针通过）
  RECOVER      移动后 → 强制 TAOM 重锚定 + SVL
```

动作预算：

- 姿态调整：每次 ≤5°，最多 3 次；必须保持头部能看到桌面 ROI。
- 底盘：每次平移 3–5cm 或旋转 5–10°，最多 **2 次**；总位移 ≤10cm。
- 任何移动后必须重跑 TAOM 关联；若地图置信度下降，停止 BAP。
- 180s 预算下，BAP 的时间上限建议 6–8s/episode；长程任务更少。

#### 3.9.4 与 ActiveAlign 的对齐

如果启用底盘/大角度姿态：

- 训练时必须注入 **post-move observations**（随机姿态后的头部/腕部图像），否则就是 ActiveAlign 的 46.3→11.5 陷阱；
- 推理时优先用 SVL 的确定性收尾，不把 post-move 的模糊图像直接交给未对齐的 VLA；
- 先做「姿态 only」A/B；底盘 A/B 单独做，不能一起上线。

### 3.10 TZT：任务零分诊断

TZT 不是「按任务训模型」，而是**离线诊断与资源分配**；下面的权重是初始值，必须用调试结果校准：

```text
risk_i = w1·deformable_i + w2·transparent_i + w3·insertion_i
       + w4·undo_i + w5·object_count_i + w6·horizon_i
       + w7·demo_variance_i
```

用途：

- 在 32 个任务里找最可能 catastrophic zero 的 5 个；
- 优先给它们分配调试槽、数据增强和人工检查；
- 在计分跑后，用真实每任务成功率更新 risk；
- 输出「任务 × 失败原因」表：没到终局 / 到了终局但释放失败 / 被人为撤销 / 超时 / 地图丢失。

没有真实榜单时，TZT 只用公开备注、演示统计和调试槽结果；不把占位 JSON 当证据。

### 3.11 GPR-VLA：唯一学习模型与接口

#### 3.11.1 底座选择

| 底座 | 优点 | 用途 |
|---|---|---|
| **WLA-1.0-Base** 6B | Apache-2.0、G1 本体匹配、24GB 可微调 [S14] | 主底座（许可友好） |
| **LingBot-VLA 2.0 UniBot LoRA** 6.3B | 公开 33k LoRA 配方、4090 可复现、开环指标 [S13] | 复现基线/对照 |

主配置优先 WLA-1.0-Base；若 WLA 的 UniBot 微调收敛慢，用 LingBot 作为可比基线。两者都只保留**一个 checkpoint**。

#### 3.11.2 输入/输出

输入：

- 4 路 RGB（头左/右、腕左/右）；可只选头双目 + 当前操作腕，降低 token；
- 双臂关节、夹爪、`lower_body`、EE base 位姿；
- 语言（160 条复述之一）；
- 当前步骤 `s_t` 的 embedding；
- TAOM 的 2D overlay 或 map token（可选）。

输出：

- action chunk（joint 或 ee；主配置 joint，保持与公开基线可比；EE 作为 A/B）；
- 步骤谓词 logits；
- 目标/容器关键点热图 + 可见性/存在性；
- 可选的位姿残差/不确定性。

所有辅助头都与动作头共享 backbone，属于同一 checkpoint；不是第二个模型。

#### 3.11.3 控制空间选择

| 空间 | 优点 | 风险 |
|---|---|---|
| `joint` | 与公开 LingBot 基线可比；平滑、易训练 | PGL 的 Cartesian 目标要经 IK/残差注入；SVL 伺服不如 EE 直接 |
| `ee` | 直接执行 `T_B_G`，SVL/腕部伺服自然 | 绝对 EE 目标的稳定性/限位未知；与公开基线不可直接比 |

建议：**主配置 joint** 复现基线；同时训练一个 EE 变体做 A/B。若 EE 在调试槽明显更好，再切换。不要在同一提交里混用两种控制空间。

#### 3.11.4 延迟预算

| 模块 | 目标 p99 | 备注 |
|---|---:|---|
| 图像接收/去畸变 | 5ms | 4 路 480×640 |
| SAWC 更新 | 3ms | 只在需要时 PnP；常数复用 |
| TAOM 更新/优化 | 10ms | 10–20 节点 |
| WVC | 3ms | 确定性 warp |
| VLA 前向 | 350ms | 50-step chunk，公开 4090 量级 |
| SVL/谓词 | 3ms | 不含等待 |
| 总计 | **<500ms** | chunk 执行 1–2s，留出网络余量 |

动作 chunk 建议 30–50 步；`get_action` 的 p99 必须稳定，否则评测方会记录异常延迟 [S4]。

#### 3.11.5 单模型审计

- 推理期唯一学习权重：VLA backbone + 同一 checkpoint 的辅助头 + 小型 map encoder；
- 其他全部是确定性代码：PnP、EKF、图优化、渲染、状态机；
- 不在推理期加载 SAM/DINO/FoundationPose/外部 VLM；
- 离线标注工具（SAM 等）只在数据管线，权重不进提交；
- 模型卡写清每个模块、标定表、外部数据开关。

### 4.1 episode 主循环

```python
def reset():
    state = EpisodeState()
    state.step = 0
    state.taom = TAOM()
    state.sawc = load_prior_hand_eye()
    state.bap = BAP(enabled=config.bap_enabled)
    state.start_time = now()

def get_action(obs):
    state.t += 1
    state.taom.update_proprio(obs)
    state.taom.update_visual(obs, state.sawc)
    state.sawc.refine_if_possible(obs, state.taom)

    state.step = SSG.update(state.step, obs, state.taom)

    if state.bap.should_act(obs, state.taom, state.step):
        return state.bap.act(obs, state.taom, state.step)

    plan = PGL.make_plan(state.step, obs, state.taom)
    plan = OPT.attach_release_pose(plan, state.taom, state.step)
    ctx = state.taom.encode_for_policy(plan, state.sawc)
    action = policy.act(obs, ctx, step=state.step)
    return action
```

### 4.2 SAWC 标定

```python
def calibrate_sawc(frames):
    estimates = []
    for f in frames:
        if f.ee_speed > 0.1:
            continue
        P_B = triangulate_head_stereo(f.head_left, f.head_right, f.K_head, f.T_B_H)
        uv_W = detect_keypoints(f.wrist, f.K_wrist, f.dist_wrist)
        pairs = associate(P_B, uv_W)
        if len(pairs) < 8:
            continue
        T_B_W, inliers, rmse = solve_pnp_ransac(pairs, f.K_wrist, f.dist_wrist)
        if rmse > 5.0 or len(inliers) < 8:
            continue
        T_E_W = inv(f.T_B_E) @ T_B_W
        if motion_consistency_ok(T_E_W, f):
            estimates.append(T_E_W)

    if len(estimates) < 4:
        return None

    T_E_W = robust_median(estimates)
    if hand_eye_mad(estimates) > THRESH:
        return None
    return T_E_W
```

### 4.3 TAOM 更新与底座补偿

```python
def taom_update(taom, obs, sawc):
    z = observation_model(obs, sawc)          # keypoints, stereo, contact
    matches = hungarian_associate(z, taom.nodes, gate=CHI2_95)

    for node, meas in matches:
        r = meas.z - node.h()
        if chi2(r, node.S) < CHI2_95:
            node.ekf_update(meas)
        else:
            mark_change(node, meas)

    if coherent_static_shift(taom, matches):
        dT = estimate_global_shift(taom, matches)
        taom.apply_base_shift(dT)             # 人挪底座，不是物体各自移动
        return

    for node in taom.nodes:
        if node.change == "local_move":
            node.ekf_update(meas)
            SSG.invalidate_if_needed(node)
        elif node.change == "missing":
            node.existence -= DECAY
            if node.existence < MISSING_THRESH:
                SSG.mark_missing(node)
        elif node.change == "state":
            node.semantic = meas.semantic
            SSG.recheck_predicate(node)

    taom.optimize_pose_graph()
```

```python
def ssg_update(step, obs, taom):
    p = predicate_head(obs, step)
    done = combine(p, taom.relation(step), gripper_event(obs), stability(taom))
```

```python
def place(plan, taom, policy, budget=2):
    T_B_C, Sigma_C = taom.container(plan.container_id)
    T_B_G = T_B_C @ plan.H_bar
    Sigma_G = jacobian(T_B_C, plan.H_bar) @ Sigma_C @ jacobian(...).T + plan.Sigma_H

    if trace(Sigma_G) < TAU_LOW:
        mode = "direct"
    elif trace(Sigma_G) < TAU_HIGH:
        mode = "servo"
    else:
        mode = "anchor_only"

    return SVL.execute(T_B_G, mode, policy, taom, budget)
```

### 5.1 观测/动作映射

- VLA 内部再 resize 到模型输入（例如 224/256）；
- 若网络带宽成为瓶颈，优先降低 VLA 的输入，而不是降低标定图像。

### 5.3 端口、状态隔离与延迟

README 要求暴露 N 个连续端口，每端口对应一台机器人/episode，状态必须隔离 [S4]。部署建议：

- 一个共享 VLA 推理后端（批处理/请求队列），N 个轻量前端端口；
- 每个端口独立：`TAOM`、`SAWC` 在线 refine、`SSG`、`BAP` 预算、动作历史；
- 只读共享：底座权重、离线 SAWC 先验、OPT 库、任务图；
- `reset()` 必须清空所有 episode 状态，不能把上一 episode 的物体账本/步骤泄漏到下一 episode；
- 每端口健康检查 + 超时兜底：VLA 超过 p99 时返回上一 chunk 的安全保持动作，而不是阻塞。

| 抓取/释放偏移 `T_E_O` | 夹爪闭合 + EE/物体跟踪 | 夹持期间位姿传播 |
| 手眼对应 | 头腕共同观测 + PnP | SAWC 训练/验证 |
| 变化事件 | 官方 human 备注 + 合成/回放 | NRB、变化检测 |
| 稳定性标签 | 释放后 0.5s 位移/谓词 | SVL |

### 6.2 采样与规模

- 全量 33k episodes、169h；不需要全部重标。
- 每个任务抽 **200–300** 条做几何/步骤标签：32×250 ≈ **8,000 episodes**；覆盖 32 任务，而不是只做放置任务。
- 手眼对应：从上述 episodes 中自动筛「头腕共同观测」帧，预计每任务 50–150 帧；加 5% 人工抽检。
- 透明/布料任务不强行 6D：只标 2D 端点/区域，避免伪标签。
- 合成/回放只做 NRB 和姿态扰动，规模控制在真实数据的 20–30%，不让合成主导。

### 6.3 训练课程

| 阶段 | 数据 | 训练 | 退出条件 |
|---|---|---|---|
| 0 | 真实 100% | 复现 WLA/LingBot 基线 | held-out 不降 |
| 1 | +步骤/关键点标签 | 辅助头（step/kp/visibility） | 谓词 F1 +5；关键点 RMSE 达标 |
| 2 | +TAOM overlay | VLA 条件注入 overlay（不新增 token） | 放置误差下降 |
| 3 | +map token | map encoder + LoRA | 地图消融有增益 |
| 4 | +SVL/NRB | 恢复/重试数据 | human 恢复 >50% |
| 5 | +BAP post-move | 姿态扰动增强 | 遮挡子集 +10pp，总体无回归 |
| 6 | 全量 | 蒸馏/量化/延迟 | p99 <500ms |

### 6.4 损失

```text
L = L_action
  + λ1 L_step
  + λ2 L_kp
  + λ3 L_pose
  + λ4 L_calib
  + λ5 L_map
  + λ6 L_rec
  + λ7 L_stable
```

| 项 | 含义 | 初始权重 |
|---|---|---:|
| `L_action` | 动作 flow/回归（基线损失） | 1.0 |
| `L_step` | 步骤谓词 BCE | 0.2 |
| `L_kp` | 关键点热图 MSE | 0.1 |
| `L_pose` | 物体/容器位姿 Huber | 0.1 |
| `L_calib` | 手眼重投影误差 | 0.05 |
| `L_map` | map token 与几何真值一致性 | 0.05 |
| `L_rec` | 撤销后恢复动作 | 0.1 |
| `L_stable` | 释放稳定性/谓词保持 | 0.05 |

### 6.5 增强与防 shortcut

- 腕部外参扰动：±1–2cm、±3–5°，模拟跨机安装差异；
- 头部位姿扰动：waist 小角度、height 变化，模拟 BAP/post-move；
- map dropout 20%：防止 VLA 只靠地图 token；
- 关键点 dropout/遮挡 10–30%：防止只靠单帧关键点；
- 背景/位置/干扰物增强：沿用 ACP/GF，但只做真实感渲染；
- NRB 破坏→恢复对：官方备注优先，随机扰动兜底。

### 6.6 算力

| 路线 | 内容 | 估算 |
|---|---|---|
| 最小推理版 | 不重训；SAWC + TAOM overlay + PGL/OPT + SVL + SSG | 1–2 人周；单卡 4090 推理 |
| 中等 | 辅助头 + overlay 训练 | 8×H100 约 1–2 周 |
| 完整 | +map token + NRB + BAP 对齐 | 8×H100 约 3–4 周 |
| 部署 | 量化/蒸馏/多端口 | 1 周 |

公开 LingBot 配方证明 6B LoRA 在单卡 4090 上 10K steps 可跑 [S13]；但加入辅助头和多任务标签后，建议至少 8×H100 做一轮完整课程。若算力不足，优先做最小推理版，不要先训 map token。

### 7.4 真机评测协议

**调试槽优先级**：

1. **T27 StackBowls**：叠放终局 + 人拿走第二个，直接测 TAOM/SSG；
2. **T10 PlugCharger**：插入终局 + 拔起撤销，测 SAWC/SVL；
3. **T25 StoreCups**：人挪底座，测整体位移补偿；
4. **T19 ZipUp**：拉链终局 + 拉开撤销；
5. **T31 OrganizePencilCase**：3 步 + 终局闭合。

每个大版本最多 1 个调试槽；先做「SAWC/TAOM on/off」A/B，再做「BAP on/off」。若调试槽不可用，退回离线回放 + 本地小规模。

**计分跑**：

- 计划 2 次：W7 中期、W8 终期；若只允许 1 次，保留 W8。
- 提交前 4h soak：N 端口并发、状态隔离、健康检查、延迟 p99。
- 记录每任务/每轴成功率、步骤分、时长、失败分类；不要只看总分。

### 7.5 统计与诊断

- 主分析：320 trials 总体成功率；目标 +5pp。
- 配对分析：同任务同轴的成功/失败对，用 McNemar；比独立两比例检验更有力。
- 子集：human 轴 64 trials、放置类任务、透明/布料任务、长程任务；用 bootstrap 置信区间。
- task-zero：每个任务 10 trials，用 Beta-Binomial 后验；不要因为 0/10 就断言「永远零分」。
- 诊断视图：任务 × 轴热力图 + 步骤级完成率 + 失败分类（没到终局/释放失败/撤销/超时/地图丢失）。
- 不把占位榜单数字当先验；真实榜单发布后重跑功效分析。

## 8. 创新点清单（持续迭代）

> 状态：押注=本轮主线；条件=需探针/A-B；升级=旧点改造；保留=沿用；降级=保留但非主回路；砍=不做。

### I1 SAWC：头双目锚定的腕部自标定（新增，押注）

- **动机**：腕部无外参、跨机安装差异大；头双目有 58.25mm 基线和米制能力；WARP-VLA 在腕部扰动下把 π0.5 从 39.2% 提到 78.3% [S16]。
- **差异**：不用标定板、不假设固定外参；用自然操作中的头腕共同观测做 PnP + AX=XB，在线 refine；标定的是「测量仪」，不是「更多 RGB」。
- **可行性**：头双目已矫正、腕部有内参、EE 位姿可直接读；PnP/手眼都是成熟几何。
- **资源**：无额外数据；离线用 33k 中头腕共同观测帧；CPU/GPU 几毫秒。
- **步骤**：离线拟合头部位姿 → 头腕对应 → PnP → 手眼聚合 → 在线 EKF → 留出验证。
- **风险**：无纹理/透明/共同观测少 → 2D fallback；头部位姿恢复误差 → 常数 fallback。
- **状态**：押注。

### I2 TAOM：桌面物体位姿账本（新增，押注）

- **动机**：Ledger 64.3% vs 45.9%，object permanence 86.7% vs 56.2% [S18]；OASIS-Map 变化检测 F1 0.783/0.667 [S19]；DAF 专门处理数据关联错误 [S20]；LLM-Enhanced Object SLAM 在稀疏观测下 mapping +36.8% [S21]；EchoVLA 的 scene/episodic memory 在移动操作上 +0.20/+0.11 [S22]。
- **差异**：不做稠密 SLAM；只做 10 节点左右的物体账本；显式区分「底座整体位移」与「物体局部移动」；把步骤谓词接进图优化。
- **可行性**：桌面场景小、刚体多；头双目可三角化；VLA 辅助头可给关键点；图优化 <10ms。
- **资源**：离线几何标签 8k episodes；无推理期外部模型。
- **步骤**：关键点/点云 → 节点/协方差 → 关联 → 变化检测 → 底座补偿 → 位姿图 → overlay/token。
- **风险**：透明/布料失效 → 2D fallback；相同物体关联错 → 多峰/步骤先验。
- **状态**：押注。

### I3 WVC：腕部视角规范化（新增，押注）

- **动机**：腕部视角随手臂变化、安装差异大；Cloak 证明 mask 夹爪区域能提升跨 embodiment 迁移 [S25]；SaPaVe 证明腕部有独立增益 [S15]。
- **差异**：不是简单 crop，而是「地图条件」的米制窗口 + 方向规范化 + 夹爪 mask；训练时模拟外参扰动。
- **可行性**：确定性 warp；内参已知；地图给深度/目标。
- **资源**：无额外模型；图像变换几毫秒。
- **步骤**：去畸变 → 地图投影裁剪 → 方向对齐 → 夹爪 mask → 训练增强 → A/B。
- **风险**：裁剪掉任务上下文 → 默认只做 overlay；canonical crop 需 A/B。
- **状态**：押注（默认 overlay，crop 条件开启）。

### I4 BAP：姿态优先/底盘最后的主动感知（新增，条件押注）

- **动机**：SaPaVe 固定相机 36.17% → 主动相机+腕部 73.16% [S15]；ActiveAlign 警告未对齐移动 46.3→11.5% [S17]；ActivePose 的 next-best-view [S24]；B* 的 base placement [S28]。
- **差异**：在 UniBot 的 API/演示约束下，把「步态」翻译成「waist/height 优先、底盘最后」；用 pivot 探针决定是否启用；不做足端规划。
- **可行性**：`height/p4` 在 FoldTowel 有演示；waist 在 `lower_body`；底盘命令存在但 OOD。
- **资源**：调试槽探针；训练时 post-move 增强。
- **步骤**：探针 → 姿态 only A/B → 底盘 A/B → 预算/安全门 → 上线。
- **风险**：分布漂移、底盘不可控、180s 超时；默认关闭。
- **状态**：条件押注。

### I5 SSG + NRB：步骤状态与撤销恢复（升级）

- **动机**：官方步骤公开；human 备注多为撤销/平移；成功率是 binary。
- **差异**：SSG 从「部分分优化」改为「诊断 + 恢复触发器」；NRB 用官方备注构造破坏→恢复，不只做数据增强。
- **可行性**：步骤文本/权重直接可读；备注可场景化。
- **资源**：无额外模型；NRB 合成/回放。
- **步骤**：任务图 → 谓词头 → 状态机 → 回滚 → NRB 训练 → 真机 A/B。
- **风险**：谓词噪声/遮挡假撤销 → 滞回 + TAOM 存在性；备注编号未知 → 通用扰动兜底。
- **状态**：升级/保留。

### I6 PGL + OPT + SVL：放置闭环（保留，接 TAOM）

- **动机**：终局放置是 success 门；少量演示的容器系释放位姿可迁移；释放后必须验证。
- **差异**：OPT 的不确定性来自演示离散度 + 容器协方差；SVL 用 TAOM 做 settle 验证；不复制轨迹。
- **可行性**：EE 位姿/容器几何/腕部近场都可得。
- **资源**：离线统计；无梯度。
- **步骤**：容器系 → H_i 库 → 在线 H̄/Σ → PGL 锚点 → SVL 预算。
- **风险**：透明/小件容器位姿失败 → 2D/SVL；释放后滚动 → 重试预算。
- **状态**：保留/升级。

### I7 TZT：任务零分诊断（新增，工程策略）

- **动机**：5 个 task zero = −15.6pp；公开基线族往往没有按任务 triage。
- **差异**：不是按任务训模型；用风险分和调试结果分配资源。
- **可行性**：官方步骤/备注/演示统计即可；无需真实榜单。
- **资源**：离线脚本 + 调试槽。
- **步骤**：风险分 → zero 列表 → 失败分类 → 调数据/调试 → 更新。
- **风险**：过拟合占位数据 → 只用真实调试结果更新。
- **状态**：新增/工程。

### I8 map token / overlay 接口（新增，需训练）

- **动机**：VLA 需要跨帧状态，但不能把完整地图塞进上下文。
- **差异**：overlay 是零训练安全版；map token 是训练版；两者可独立开关。
- **可行性**：10 个物体 × 4–8 token，长度可控；MLP 属于同一 checkpoint。
- **资源**：辅助头/ map encoder 训练；8×H100 1–2 周。
- **步骤**：overlay A/B → token 训练 → map dropout → 延迟。
- **风险**：模型过度依赖地图/地图错误 → dropout + 置信度门控。
- **状态**：条件/训练。

### I9 DebugLoop（保留）

- **动机**：真机反馈比自建孪生可信；官方有不计分单任务调试。
- **差异**：制度化：任务选择、A/B、判定标准、记录表单；加 pivot 探针。
- **资源**：调试槽次数未知；每版本最多 1 次。
- **风险**：资源稀缺 → 离线回放兜底。
- **状态**：保留/流程。

| SAWC 标定误差大 | 中 | 高 | 头双目锚定 + RANSAC PnP + 多帧聚合 + 在线 refine | 重投影 >5px 或手眼漂移 >1cm/2° → 关度量地图 |
| 头部位姿 API 不可得/拟合差 | 高 | 中 | `lower_body` + 离线 `T_T_H`/waist 回归；常数 fallback | 头部重投影 >1cm → 只用 2D/近似 |
| 腕部跨机安装差异 | 高 | 中 | WVC + 在线 refine + 夹爪 mask | 调试槽无增益 → 关 WVC |
| 透明/布料地图失效 | 高 | 中 | 分桶：刚体开 TAOM；透明/布料只做 2D/SVL | 地图置信度低 → 自动回退 |
| 底座被人挪动 | 中 | 高 | 静态物体一致性估计 `ΔT_B` | 全局位移估计不稳 → 冻结地图 |
| BAP 分布漂移 | 中 | 高 | 姿态优先、底盘最后；post-move 训练；≤2 次 | 探针失败或总体下降 → 关 BAP |
| pivot 语义误解 | 高 | 高 | 不计分探针；一次只改一通道 | 无可见效果/保护 → 禁用 |
| 单模型审计 | 中 | 高 | 唯一 VLA checkpoint；辅助头同模型；其余确定性；模型卡 | 审计不过 → 去 map token，只留 overlay/SVL |
| 外部数据违规 | 低 | 高 | 默认 OFF；邮件确认 | 明确禁止 → L2L 转赛后 |
| 延迟/并发 | 中 | 高 | 共享后端 + 每端口状态隔离；p99 压测 | p99 >500ms → 降 token/降分辨率 |
| 统计噪声 | 高 | 中 | 320 trials + 配对 McNemar/bootstrap；目标 +5pp | CI 跨 0 → 不上线 |
| 过拟合占位榜单 | 高 | 中 | 不把占位数字当先验；真实榜单后重跑 | 发现依赖占位 → 回退 |

## 12. 开放问题

1. `pivot_3/4/5` 的官方语义是什么？`height` 是否是腰部高度而非底盘 z？必须用调试槽探针确认。
2. `action.pivot` 在评测器里是否真的执行？如果只执行手臂、忽略底盘，BAP 的底盘分支应永久关闭。
3. 头部相机是否与 torso 刚性连接？`state_d435` 的变化是否完全由 waist 解释？这决定 SAWC 的米制精度。
4. N 台评测机器人的准确数量、每端口并发/延迟上限；共享后端能否满足 p99。
5. 不计分单任务调试的可用次数/成本/是否允许自定义场景探针。
6. 外部数据（自采/实验室数据）是否允许？预训练权重（含论文方法）是否允许？
7. 单模型边界：辅助头、map encoder、离线标定表是否需在模型卡披露？倾向全部披露。
8. 终局步是否严格是 success gate？步骤分的聚合公式是什么？
9. 官方是否提供物体/容器 CAD 或尺寸？没有的话，容器系拟合的误差上限要重估。
10. human 备注的编号（human_1/human_4/unseen_object_3）是轴编号还是试次编号？评测是否就在这些剧本里采样？
11. 透明/布料任务是否允许只做 2D 锚点，还是官方 success 需要 6D 精度？
12. 真实榜单发布后，top 是否仍 <30%？若 top 明显更高，WRIST-MAP 的收益上限要重估。
