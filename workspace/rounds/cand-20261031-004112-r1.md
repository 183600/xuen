# 第 13 轮 · CSK-RUBRIC：把官方 94 个评分步骤编译成常识契约，补上「第一个 3 秒」的语义/程序瓶颈

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是第 13 轮（灵感循环第 3 轮），三个词是「**常识推理**」「**开源生态**」「**场景泛化**」。本轮不推倒第 12 轮 CHUNK-SERVO，也不重训第 10/11 轮的 FACT-VLA / GEO-RESIDUAL；而是把 CHUNK-SERVO 从「控制层」再往上补一层「**任务语义/程序层**」：**CHUNK-SERVO 管最后 3 厘米，CSK-RUBRIC 管第一个 3 秒。**

## 0. 先给结论：30% 的天花板不是单点，而是「第一个 3 秒」和「最后 3 厘米」两段

第 12 轮我把榜首不到 30% 归因于 30 步开环 chunk 和最后 3 厘米的接触误差。这个判断仍然成立，但本轮补查官方任务页后，我发现它只解释了一半：

1. **官方 32 个任务页不是只有任务名，而是每个任务都公开了 `info.json`**：里面有 2–5 个评分步骤、每步分值、难度、以及 `generalization` 字段（未见物品、人为干扰的具体做法）。32 个任务合计 **94 个评分步骤**，其中 **25/32 个任务的最后一步占 40–50 分**，**7 个任务是 4–5 步、每步 20–25 分**。这不是一张“难度表”，而是一份**免费的任务程序规范**。[S2][S17]
2. **人为干扰不是“把物体挪一下”这么简单**。官方 `generalization` 明确写了“把拧开的盖子拧回去”“把叠好的毛巾翻开”“拉上拉链之后拉开”“叠了第二个之后拿下第二个”“中途把锁拿走”“把网线另一头也插上”“把食物放回传送带起点”。这些是**撤销已完成子目标、移除目标、增加前置条件、动态重置**，不是几何扰动。视觉伺服能看到“物体动了”，但不知道“任务进度被撤销了”。[S17]
3. **开源证据表明 VLA 的常识/语义在动作微调后确实会掉**。Act2Answer 在 9 个 VLA、12 类、1,720 道二选题上发现：简单颜色/形状还在，但情感、属性、状态、时间、计数、对称、交通、公共信息、名人、生物世界等类别接近随机；VLM 基线可比对应 VLA 高 20–40 分；VQA 联合训练与更好的知识保留相关。[S18] RoboSemanticBench 更直接：VLA 能抓起候选方块，但在控制抓取成功后，选对“语义正确答案”的比例接近或低于随机。[S19] RoboSPA 在 280 个变体、527K 轨迹上发现，最难层级所有模型平均成功率低于 25%，π0.5 只有 22.3%，失败集中在目标 grounding、低层操作、长程跟踪和记忆。[S20]
4. **所以 30% 不是“某个模型不够大”，而是两段共享瓶颈**：
   - **第一个 3 秒**：抓错物体/角色、选错受器、漏掉前置条件（先拧盖再倒药、先对齐拉链头再拉）、长程顺序错、被人为撤销后继续按旧进度执行。
   - **最后 3 厘米**：插入、挂杯、叠碗、拉拉链、拧盖、开锁的接触/对齐误差。
   第 12 轮的 CHUNK-SERVO 解决第二段；本轮要解决第一段。

**本轮押注：CSK-RUBRIC（Commonsense Rubric Contract）。**

> 把官方 94 个评分步骤、32 条任务语言、以及 `generalization` 里的未见物品/人为干扰说明，离线编译成一张**带前置条件、效果、撤销边、物体角色、恢复策略的任务契约图**；用同一份契约做五件事：① 给 WLA 编译“当前子目标”提示；② 把 33k 成功演示对齐到子目标；③ 在 WLA 动作头上加一个**进度头**，在线检测“进度回退/被人为撤销”；④ 用开源常识基准做**常识回放**，防止动作微调把语义能力洗掉；⑤ 用官方步骤分值做**步骤分投资组合**，决定先修哪个任务的哪一步。

一句话：**把“官方评分表”变成“可执行的常识契约”，让模型不仅知道“怎么做”，还知道“现在做到哪、这一步的前置条件是什么、被人拆掉后该退回哪一步”。**

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **常识推理** | 契约图的前置条件/效果/撤销边；子目标提示；进度头；Act2Answer/ERQA-Plus/RoboSemanticBench 常识回放 | 不做第二个在线学习模型；不把常识做成一个独立 LLM 在线调用 |
| **开源生态** | 用 WLA/ER-1/ER-Flow、LeRobot v3.0、HF 数据集、IsaacLab/MuJoCo、开源 VLM 基准做离线编译/回放/评测；发布契约编译器 | 不把多个开源模型混在一起在线推理；不假设开源榜单分数=真机分数 |
| **场景泛化** | 角色化提示（“带把手的杯子”而不是“红杯子”）；背景/干扰物/外观增强；目标相对表示；五类泛化轴分诊 | 不做完整 sim-to-real 策略训练；不把训练集里的 canonical 场景当成评测分布 |

## 1. 本轮新核实的事实（只列会改变方案的）

### 1.1 官方 32 个任务页公开了 94 个评分步骤、分值和泛化说明（A 级）

我逐个抓取了 `tasks_v2/<slug>/info.json`（示例：[HangCup](https://unibot.unitree.com/tasks_v2/hang_the_cup/info.json?v=2026-07)、[PlugInEthernet](https://unibot.unitree.com/tasks_v2/plug_in_ethernet/info.json?v=2026-07)、[OrganizePencilCase](https://unibot.unitree.com/tasks_v2/pencil_case/info.json?v=2026-07)，共 32 个；Jina 读取到的 `Published Time` 为 2026-10-08，本轮 2026-10-31 复核）。汇总结果：

| 项 | 数值 |
|---|---:|
| 任务数 | 32 |
| 评分步骤总数 | **94** |
| 难度 | Easy 12 / Medium 12 / Hard 8 |
| 2 步任务 | 11 |
| 3 步任务 | 14 |
| 4 步任务 | 5 |
| 5 步任务 | 2（FoldTowel、OrganizeStationery） |
| 最后一步 ≥40 分的任务 | **25/32** |
| 最后一步 50 分的任务 | 11 |
| 最后一步 40 分的任务 | 14 |
| 4–5 步、每步 20–25 分的任务 | 7（ToolboxStorage、OrganizeTools、FoldTowel、OrganizeStationery、PackBag、SpellRobot、StoreEarphones） |

这不是“所有任务都是最后一步定胜负”：**25 个任务是 final-heavy（最后一步 40–50 分），7 个任务是 balanced（4–5 步、每步 20–25 分）**。对前 25 个任务，成功几乎等于最后一步；对后 7 个任务，早期步骤的步骤分同样值钱。这个区分直接改变竞赛投资组合（见 §3.7）。

### 1.2 官方 `generalization` 字段给出了人为干扰的具体做法，其中 12 个任务包含“撤销/移除/动态重置”（A 级）

`info.json` 的 `generalization` 至少包含一个 `unseen_object_3` 和两个 `human_*_note`。我把 32 个任务的人为干扰归成五类：

| 类型 | 例子（官方原文） | 任务 | 对方案的含义 |
|---|---|---|---|
| **移动目标/受器** | “杯子向后”“水果向右”“把网线移开”“把插口移开” | 多数任务 | 重定位 + 相对目标；第 12 轮 DG-KEYFRAME 已覆盖 |
| **抓取后移动受器/底座** | “抓到书后挪动架子”“抓电池之后动绿色盒子”“放了第一个马上放第二个挪一下底座” | T08、T11、T25 | 夹爪/物体刚体假设失效；需要重估受器并重抓/重放 |
| **撤销已完成步骤** | “拧开盖子之后拧动回来”“将叠完的毛巾翻开”“笔盒合上之后手动打开”“拉上拉链之后拉开”“叠了第二个之后拿下第二个” | T14、T16、T17、T19、T27 | **进度回退检测**；视觉伺服无法知道“这一步被撤销了” |
| **移除目标/增加前置条件** | “中途把锁拿走”“把网线另一头也插上” | T12、T05 | 目标消失/任务变难；需要契约重规划或安全失败 |
| **动态重置** | “可乐快到了然后放回传送带起点”“薯片快到了然后放回传送带起点” | T24 | 动态目标跟踪；不能假设物体静止 |

这五类里，**撤销已完成步骤 6 个**（T10 插头被拔起、T14 盖子被拧回、T16 毛巾被翻开、T17 笔盒被打开、T19 拉链被拉开、T27 第二个碗被拿走），**移除目标/增加前置条件/动态重置 4 个**（T05 另一头也被插上、T12 锁被拿走、T24 食物被放回起点、T29 外壳盖被移开），**抓取后移动受器/底座 3 个**（T08、T11、T25），合计 **13 个任务**不是“重定位一下”能解决的。它们需要一个**任务进度状态机**，而不是一个更准的位姿估计器。

### 1.4 提交 API 是 v2：`obs_delta_indices` 逐键堆叠，`action_chunk_size` 固定；WLA server 支持逐请求 `instruction`（A 级）

- 提交模板当前 README（commit `edd0a1c9`，2026-08-21，“version 2, support observation-based frame-skipping stacking, image scaling…”）使用 `obs_delta_indices`（每个观测键的帧偏移列表）和 `image_resize`；不再是最早的 `data_keys` / `obs_chunk_size` 单值接口。旧接口的笔记必须剪掉。[S7][S8]
- `action_chunk_size` 是每次 `get_action` 返回的 leading time-axis 长度；index 0 先执行，其余顺序执行，直到 evaluator 再次调用；chunk 内没有新观测。评测跨 N 台机器人，必须从 8765 起暴露 N 个连续端口；每端口独立；`reset()` 必须隔离；token 每次 `get_action` 都要带；评测端记录延迟/波动/动作统计。[S7][S8]
- **WLA 模型服务器的 `_build_example` 明确读取 `obs.get("instruction") or obs.get("task") or self.instruction`**，并把它作为 `lang` 送入模型。这意味着我们可以在**不改 VLM、不重训**的情况下，把“当前子目标提示”逐请求注入 WLA；这是 CSK-RUBRIC 的关键接口事实。[S15]
- WLA server 期望 `left_ee_6d`/`right_ee_6d` 为 xyz+rot6d（9 维），挑战赛 API 给的是 xyz+rpy（6 维）；adapter 必须做 rpy→rot6d，并把 WLA 输出的绝对 EE xyz+rpy 映射回挑战赛的 `*_ee_pose_gripper_base`。WLA server 只用 `cam_left_high` + 左右腕部三路图；`cam_right_high` 留给双目/伺服。[S15]

### 1.5 开源生态已经把“基座”商品化；差异化在数据/契约/执行层（A+B 级）

- **UnifoLM-WLA-1.0**：6B，约 2,500 h 真机数据，64 任务，54 维动作，默认 `chunk_size=30`、`target_fps=30`、4 步扩散；冻结 VLM、只训 DiT action head + robot-state projector，单张 24GB GPU 可跑；2026-09-28 开源 Base 权重与微调代码，2026-09-29 加 LoRA；Apache 2.0。[S13][S14][S16]
- **UnifoLM-ER-1 / ER-Flow**：4B 具身推理基座；官方开源计划里与 WLA 并列。[S13]
- **数据**：UniBot-V1 Challenge Dataset 32 个数据集，Apache 2.0，LeRobot v3.0 格式；另有 UnifoLM-WBT、UnifoLM-Dex1 数据集。[S11]
- **仿真/工具**：`unitree_sim_isaaclab`、`unitree_mujoco`、`unitree_rl_mjlab`、`unitree_rl_lab`；LeRobot 生态。[S30][S33]
- **结论**：如果大家都用 WLA + 同一份 33k 数据，基座不会拉开差距；差距来自**任务契约、提示、演示对齐、恢复策略、场景增强、评测方法**。这正是本轮把工程投到“语义/程序层”的理由。

### 1.6 榜单仍然是“预览/合成”，不能当真实失败分布（A+B 级）

2026-10-31 复核：官网榜单仍是 8 个模型，MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%；`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`；`runs.html` 显示 256 条（8×32），详情页视频仍是“测试视频占位”；每任务只有 10 次 trial，但成功率出现 27.29%、27.85%、38.43% 等非 10% 整数倍。[S3][S4][S5][S6]

**结论不变**：29.7% 只能当“赛事方预览上限/难度信号”，不能当 SOTA、任务难度表或失败分布。本轮不从榜单任务排名挖创新点；本轮从**官方任务 rubric + 数据 + 开源模型接口**挖。

- 真实任务成功率/失败分布（榜单是预览，不能反推）。

## 2. 诊断：把失败拆成 F1–F5，看到「第一个 3 秒」的真实份额

### 2.1 五类失败与五类泛化轴的映射

| 失败类型 | 典型表现 | 对应泛化轴 | 本轮对策 |
|---|---|---|---|
| **F1 目标/角色错** | 抓了干扰物、抓了杯身而不是杯把、把“网口”当成“网线” | 未见物品、干扰物、背景 | 角色化提示 + 同 checkpoint 角色 grounding（watch） |
| **F2 子目标/顺序错** | 先倒药再拧盖、先拉拉链再对齐、长程任务漏步 | 位置、未见物品、长程 | 契约图 + 子目标提示 + 进度头 |
| **F3 前置条件/affordance 缺失** | 盖子没拧开就倒、插头方向反了、拉链头没咬合 | 未见物品、人为干扰 | 契约前置条件 + 证据门控 |
| **F4 进度被撤销/目标被移除** | 人把盖子拧回去、把毛巾翻开、把锁拿走、把食物放回起点 | 人为干扰（20% trials） | 进度回退检测 + 撤销边 + 恢复库 |
| **F5 最后 3 厘米接触误差** | 插不进、挂不上、叠不稳、拉链卡住 | 位置、人为干扰 | 第 12 轮 CHUNK-SERVO |

F1–F4 是“第一个 3 秒”的问题；F5 是“最后 3 厘米”的问题。两者共享同一个执行循环，但需要的信号不同：F5 需要几何/视觉伺服，F1–F4 需要**任务状态/语义**。

### 2.2 为什么“更大的 VLA”不自动解决 F1–F4

- Act2Answer：VLA 在动作微调后，富语义类别接近随机；VLM 基线高 20–40 分；VQA 联合训练有帮助。[S18]
- RoboSemanticBench：VLA 能抓起候选块，但选对语义答案接近/低于随机；说明“会抓”不等于“懂选哪个”。[S19]
- RoboSPA：最难层级所有模型 <25%，π0.5 22.3%；失败在目标 grounding、长程跟踪、记忆。[S20]
- ADAPT：真实环境有未指定的 affordance 约束；智能体需要感知物体状态、推断隐式前置条件；一个 LoRA 微调的 VLM 做 affordance 后端比 GPT-4o 更好。[S22]
- 这些证据共同说明：**语义/程序能力不是“参数量”问题，而是“训练信号/接口”问题**。官方 rubric 正好提供了每任务的前置条件/子目标/分值，但没人把它变成训练/运行时信号。

### 2.3 为什么“场景泛化”不能只靠更多真实数据

- UMI-Bench 把 unseen 条件拆成 Factor A（物体/外观/类别/组合）和 Factor B（位置/布局/位姿/动力学），并分别报告 seen/unseen 与 generalization gap。[S24]
- ManipArena 的 10 次 trial 是分层设计：T1–T4 in-domain、T5–T8 视觉偏移、T9–T10 语义 OOD；例如勺子从不锈钢→儿童勺→黑色塑料勺。[S25]
- LIBERO-Plus 用 416 个干扰物和 target pose 扰动做渐进鲁棒性测试。[S26]
- RoboPRO 用 80 个双臂任务、16,000 条演示、不同干扰物密度做 perturbation-resilient 评测。[S27]
- RoboAug 用区域对比数据增强，把背景/干扰物/光照三因素下的成功率从 0.09→0.47、0.16→0.60、0.19→0.67（三个机器人）。[S28]
- 这些工作说明：**场景泛化可以被“分轴”测量和“分轴”增强**，不需要一个黑盒大模型硬吃。官方 5 轴正好给了分轴评测协议；我们可以用开源增强/回放分别打。

### 2.4 为什么“开源生态”是杠杆也是陷阱

- 杠杆：WLA 基座、33k 数据、LeRobot、IsaacLab/MuJoCo、ER-1/Flow、开源 VLM 基准都可离线用；不用从零训 6B。
- 陷阱：如果在线上把 WLA + 一个开源 VLM + 一个开源检测器“拼”起来，既违反单模型规则，也会把延迟/故障率放大。
- 正确姿势：**离线用生态，线上只跑一个 checkpoint + 确定性契约/控制器**。这也是本轮所有创新点的合规底线。

## 3. 方法：CSK-RUBRIC

### 3.1 核心表示：任务契约图（Task Contract Graph）

对每个任务 $t$，把官方 rubric 编译成：

```text
Contract(t) = {
  roles:        {object_id -> role, affordances, must_grasp/must_align}
  subgoals:     [{id, text_zh/en, weight, preconditions, effects, evidence, recovery}]
  edges:        [(i -> j)]                  # 正常顺序
  undo_edges:   [(i -> j, condition)]       # 观察到 i 的效果被撤销 -> 退回 j
  success:      [final effects]
  human_cases:  {move/undo/remove/add/dynamic -> recovery policy}
}
```

以 T26 PlugInEthernet 为例（官方 30/30/40）：

```json
{
  "task_id": "T26",
  "roles": {
    "cable": {"role": "target", "affordance": ["connector", "flexible"], "grasp": "connector_body"},
    "port":  {"role": "receptacle", "affordance": ["opening", "socket"], "align": "connector_axis"}
  },
  "subgoals": [
    {"id": "G1", "text": "Grasp the ethernet cable", "weight": 30,
     "preconditions": ["cable visible", "gripper open"],
     "effects": ["cable held"],
     "evidence": ["gripper closed", "cable moves with gripper"],
     "undo_if": ["cable no longer held"], "recovery": ["re-localize cable", "re-grasp"]},
    {"id": "G2", "text": "Hold the network port", "weight": 30,
     "preconditions": ["port visible", "cable held"],
     "effects": ["port stabilized"],
     "evidence": ["port pose stable", "cable near port"],
     "undo_if": ["port moved by human"], "recovery": ["re-localize port"]},
    {"id": "G3", "text": "Plug the cable into the port", "weight": 40,
     "preconditions": ["connector aligned with opening", "cable held", "port stabilized"],
     "effects": ["connector seated"],
     "evidence": ["insertion depth", "cable no longer free", "contact stable"],
     "undo_if": ["cable unplugged"], "recovery": ["re-align", "re-insert"]}
  ],
  "edges": [["G1","G2"],["G2","G3"]],
  "undo_edges": [{"from":"G3","to":"G1","condition":"cable unplugged"}]
}
```

以 T19 ZipUp 为例（官方 50/50，人为干扰“拉上拉链之后拉开”）：

```json
{
  "task_id": "T19",
  "roles": {
    "pouch": {"role": "target", "affordance": ["zipper", "fabric"], "grasp": "pouch_body"},
    "zipper_pull": {"role": "tool", "affordance": ["pull_tab"], "grasp": "pull_tab"}
  },
  "subgoals": [
    {"id": "G1", "text": "Straighten the storage pouch", "weight": 50,
     "preconditions": ["pouch visible", "zipper accessible"],
     "effects": ["pouch aligned", "zipper track visible"],
     "evidence": ["pouch axis aligned", "zipper track straight"],
     "undo_if": ["pouch moved"], "recovery": ["re-localize", "re-straighten"]},
    {"id": "G2", "text": "Zip it up", "weight": 50,
     "preconditions": ["zipper pull engaged", "track aligned"],
     "effects": ["zipper closed"],
     "evidence": ["pull reached end", "teeth closed"],
     "undo_if": ["zipper opened by human"], "recovery": ["re-engage pull", "re-zip"]}
  ],
  "edges": [["G1","G2"]],
  "undo_edges": [{"from":"G2","to":"G2","condition":"zipper reopened"}]
}
```

契约不是“自然语言提示”，而是**可执行的证据/撤销/恢复结构**；LLM 只负责离线起草，人负责审 94 个步骤。

### 3.2 离线编译器：用开源生态做“常识编译”，但不在线加载

```text
输入：32 个 info.json + 任务语言 + 33k 演示 + 官方 generalization 说明
  │
  ├─ Step 1 解析 rubric：子目标、分值、难度、unseen/human 说明
  ├─ Step 2 LLM/VLM 起草契约：角色、affordance、前置条件、效果、undo 边
  │    （Qwen3-VL / UnifoLM-ER-1/Flow 均可，离线；输出 JSON Schema）
  ├─ Step 3 演示对齐：动作/状态 change-point + 腕部/头部视觉变化 + 关键帧描述
  │    → 每帧/每段一个子目标标签；动态规划保证单调；人工抽检 10%
  ├─ Step 4 人工审 94 个步骤：前置条件/效果/undo 边/恢复策略
  ├─ Step 5 生成提示变体：角色化、程序化、负约束、简短/详细两版
  ├─ Step 6 生成回放/增强数据：常识 VQA、背景/干扰物/外观增强
  └─ 输出：contracts/*.json、subgoal_labels.parquet、prompts/*.jsonl
```

关键点：

- **LLM 只离线用**：编译完就固化；线上不加载 LLM/VLM 教师，避免“第二个模型”。
- **94 个步骤是可控的标注预算**：1–2 人天可完成首轮人工审；比标 33k 条演示便宜得多。
- **演示对齐不是“再训一个模型”**：用确定性 change-point + 动态规划 + 离线 VLM 关键帧描述；输出是标签，不是在线策略。
- **契约可版本化**：每个任务一个 JSON，改动可 diff；单任务通道失败时可以定位到“哪条前置条件/undo 边写错了”。

### 3.3 在线：一个 checkpoint + 一个确定性契约监视器

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)       │
                    │  ├─ prompt compiler (lookup)        │
                    │  ├─ contract monitor (state machine)│
                    │  ├─ progress head (same ckpt)       │
                    │  ├─ recovery library                │
                    │  ├─ CHUNK-SERVO (round 12)          │
                    │  └─ WLA adapter (54D -> 21D)        │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared WLA server (GPU)            │
                    │  6B VLM + DiT action head           │
                    │  + progress head (same checkpoint)  │
                    └─────────────────────────────────────┘
```

**唯一学习模型**：WLA（含动作头 + 进度头，同一个 checkpoint）。
**确定性组件**：契约状态机、提示查表、恢复脚本、CHUNK-SERVO 视觉伺服。
**离线组件**：LLM/VLM 编译器、演示对齐、增强/回放数据；不进入线上。

### 3.4 进度头 CSK-PROGRESS：让模型自己说“现在做到哪”

在 WLA 的 action model 隐状态上接一个小的分类头（2–5 类，按任务的子目标数），用 §3.2 对齐出的子目标标签训练。它和动作头共享同一个 VLM/action backbone，**不是第二个模型**。

- 输出：`p(subgoal | obs)`，以及熵 `H_t`。
- 训练：交叉熵 + 标签平滑；与动作损失联合训练，权重 $\lambda_p$（先 0.1–0.3）。
- 在线：
  - `expected_i` 来自契约；`pred_i = argmax p`。
  - 若 `pred_i < expected_i` 连续 K 帧（默认 K=3），且契约有 `undo_edge(expected_i -> pred_i)`，判定**进度回退**，触发恢复。
  - 若熵 `H_t > θ_H`，判定**语义不确定**，触发“更详细的子目标提示/重定位/安全 hold”。
- 为什么比几何编辑检测好：它直接学“任务处于哪个子目标”，不需要手工定义“场景动了但不是我动的”；人为撤销、目标移除、抓取后移动受器都可以表现为进度分布变化。
- 风险：进度头可能过拟合 canonical 场景；用场景增强 + 温度校准 + 契约证据交叉验证。

### 3.5 提示编译器：把 rubric 变成 WLA 能吃的“当前子目标”

WLA server 支持逐请求 `instruction`（§1.4），所以不需要重训 VLM 就能注入提示。模板示例：

```text
Task: Plug the Ethernet cable into the network port.
Current subgoal 3/3 (40 pts): Insert the connector into the port opening.
Object roles: target = cable with connector; receptacle = port with opening.
Preconditions: connector aligned with opening; cable held; port stabilized.
Previous subgoal: port stabilized.
If the scene changed, re-localize the port before inserting. Do not grasp the distractor cable.
```

三个变体：

1. **短提示**：只加“Current subgoal i/n: …”，用于验证语言条件是否有效。
2. **角色化提示**：把“红杯子/塑料架子/黑网线”换成“带把手的杯子/带标记槽的架子/带接头的网线”，针对未见物品。
3. **负约束提示**：明确“不要抓干扰物/不要抓杯身”，针对干扰物。

所有变体离线生成、人工审；在线只做字符串查表，CPU 开销可忽略。单任务通道先做 A/B：raw language vs 短提示 vs 角色化 vs 负约束。

### 3.6 训练：CSK-REPLAY + rubric-weighted loss + 场景课程

**CSK-REPLAY（常识回放）**：Act2Answer 的结论是 VQA 联合训练与知识保留相关。[S18] 我们可以：

- **REPLAY-A（便宜）**：冻结 VLM，在 action head 上加一个辅助“子目标/角色分类”损失，用 rubric 标签 + 合成角色描述训练；让动作头学会使用 VLM 的语义特征。
- **REPLAY-L（推荐，若显存允许）**：对 VLM 做 LoRA，混入 5–10% 的常识/具身推理数据（ERQA-Plus、Act2Answer 风格、RoboSemanticBench 风格），语言建模损失 + 动作损失联合训练；WLA 已支持 LoRA。[S13][S16]
- **REPLAY-D（可选）**：用更大的开源 VLM/ER-1 离线蒸馏到 WLA 的 VLM LoRA；线上仍只有一个 checkpoint。这是“训练时教师”，不是“测试时混模型”，但需向官方确认解释。

**Rubric-weighted loss**：用对齐后的子目标标签，把动作损失按官方分值加权：

$$\mathcal L = \sum_{t} \sum_{i \in \text{subgoals}(t)} w_{t,i} \cdot \ell_{\text{action}}(t,i) + \lambda_p \mathcal L_{\text{progress}} + \lambda_c \mathcal L_{\text{replay}}$$

- $w_{t,i}$ 先按官方分值归一化（如 30/30/40 → 0.3/0.3/0.4），再做温度平滑，避免最后一步过拟合。
- **子目标平衡采样**：对稀有/难子目标（拉链、锁、针管、开盖）过采样；对简单子目标设上限。
- 风险：最后一步过拟合会伤早期步骤；用验证集和单任务通道监控。

**场景课程（scene curriculum）**：按五轴从易到难：

1. 背景替换（真实前景 mask + 其他桌面纹理）；
2. 干扰物 copy-paste（从其他 episode/开放数据取物体，放在工作空间边缘→路径附近）；
3. 目标外观替换（颜色/材质/尺寸；用分割 mask 做 compositing）；
4. 位置偏移（目标/受器平移/旋转；配合目标相对表示）；
5. 遮挡/人手进入/目标移除（用合成遮挡 + 契约恢复；不追求照片级真实）。

增强数据只用于训练，线上仍是一个 checkpoint。先用开源增强/分割工具（RoboAug 思路、SAM 离线）做第一版，再在单任务通道验证是否真涨点；不假设生成数据一定有用。

### 3.7 竞赛策略：用官方步骤分值做“步骤分投资组合”

排名先看成功率，成功率相同看步骤分。官方 rubric 给出每步分值，所以我们可以把工程投资写成：

$$E[S_t] = \sum_i w_{t,i} P(\text{reach } i), \qquad P(\text{success}_t) = P(\text{reach } n_t)$$

- **Tier A（final-heavy，25 个任务）**：最后一步 40–50 分；成功几乎等于最后一步。优先 CHUNK-SERVO + 最后一步子目标提示 + 接触恢复。
- **Tier B（balanced，7 个任务）**：ToolboxStorage、OrganizeTools、FoldTowel、OrganizeStationery、PackBag、SpellRobot、StoreEarphones；4–5 步、每步 20–25 分。即使最终失败，早期步骤的步骤分也能救 tie-break；优先进度头 + 早期子目标鲁棒性。
- **Tier C（human-undo，13 个任务）**：T05、T08、T10、T11、T12、T14、T16、T17、T19、T24、T25、T27、T29；人为干扰轴占 20% trials；优先进度回退 + 恢复库。
- **Tier D（metadata gap，9 个任务）**：T08、T09、T15、T16、T19、T29、T30、T31、T32 没有 `unseen_object_3` 说明；T31/T32 连 human 说明也缺。不要假设“没有未见物品变体”；单任务通道先验证，再决定是否投增强。

单任务通道协议（不计分，但决定是否烧正式提交）：

1. 选 5 个代表任务：PlugInEthernet（插入，final-heavy）、ZipUp（拉链，human-undo）、PourOutMedicine（开盖+倒，human-undo）、StackBowls（叠放，final-heavy）、FoldTowel（5 步 balanced，防回归）。
2. 每个任务 5 次 A/B：raw prompt vs CSK-RUBRIC（短提示/角色化/进度恢复）；同初始条件；记录成功、步骤分、耗时、p99、恢复次数。
3. 通过标准：≥3/5 任务步骤分 +5 或成功率 +10pp；FoldTowel 不回归 >5pp；p99 不升 >20%。
4. 再扫 `action_chunk_size ∈ {5,8,30}` 和提示变体；选最佳折中。
5. 最后才跑 32×10 正式评测。

收益算术（设计目标，不是承诺）：

- 25 个 final-heavy 任务各 +5pp 成功 → `25/32×5 = +3.9pp`；
- 13 个 human-undo 任务在 human 轴 +10pp → `13/32×0.2×10 = +0.81pp`；若 32 个任务 human 轴都 +10pp → +2pp；
- 7 个 balanced 任务各 +5 步骤分 → `7/32×5 = +1.1` 步骤分；
- 保守合计 **+3–5pp 成功、+1–3 步骤分**；乐观 +6–8pp。必须用配对 A/B + bootstrap 证明，不能拿预览榜单当因果。

### 3.8 与第 12 轮的关系：保留、升级、剪枝

**保留**：

- CHUNK-SERVO：30 步规划 + 5 步视觉伺服；DG-KEYFRAME 相对目标；GEO-RESIDUAL 的接触/编辑信号；官方 WLA 基座；单任务通道。
- 第 10 轮 FACT-VLA 的相位化 BC；第 11 轮 GEO-RESIDUAL 的动作条件化残差。

**升级**：

- 观测层 → 任务层：GEO-RESIDUAL 的“编辑检测”升级为契约的“进度回退检测”；
- 开环 chunk → 双频闭环（第 12 轮）+ 子目标提示/进度头（本轮）；
- 绝对语言 → 角色化/程序化提示；
- 单一动作损失 → rubric-weighted + 常识回放 + 场景课程；
- 任务组合 → 步骤分投资组合。

**剪枝**：

- 不做从零训 VLA/World Model；WLA 已开源。
- 不做完整 sim-to-real 策略训练；增强/仿真只做训练数据和控制器风洞。
- 不做第二个在线学习模型/独立检测器/独立 VLM；契约/进度头/伺服都是同一 checkpoint 或确定性组件。
- 不做 32 个任务各一个策略；规则禁止且不泛化。
- 不做 6D 物体位姿网络；透明/变形不可靠，用角色/相对目标/证据。
- 不做力/触觉闭环；API 没有。
- 不做 30Hz 广域网伺服；用 5 步 chunk。
- 不把预览榜单的任务排名当难度表；已证伪。
- **剪掉旧 API 笔记**：`data_keys` / `obs_chunk_size` 是 v1；当前是 `obs_delta_indices` / `image_resize` / `action_chunk_size`。
- **剪掉“通用机器人数据越多越好”**：WLA 已用 2,500h；边际收益低；优先官方 33k + 任务特定增强。

## 4. 可行性：为什么现在能做

1. **官方 rubric 是公开的**：32 个 `info.json`，94 步，分值和泛化说明都可抓；契约编译的输入齐全。[S2][S17]
2. **WLA server 支持逐请求 `instruction`**：提示编译器不需要重训 VLM；先做零样本 A/B，再决定是否 LoRA。[S15]
3. **WLA 支持 LoRA + 单卡 24GB 微调**：常识回放/场景课程的成本可控。[S13][S16]
4. **33k 演示 + 94 个子目标**：演示对齐的标注预算小；进度头训练数据可从对齐标签自动生成。[S11]
5. **开源生态齐全**：ER-1/Flow 做离线教师，LeRobot/HF 做数据，IsaacLab/MuJoCo 做风洞，Act2Answer/ERQA-Plus 做常识诊断。[S13][S18][S21][S30][S33]
6. **合规路径清晰**：线上一个 checkpoint + 确定性契约/控制器；离线教师/增强/回放不进入测试时。灰色地带（LoRA soup、离线蒸馏）先邮件确认。

**最大风险**：WLA 的语言条件可能对“子目标提示”不敏感（它训练时多用短任务语言）。如果 A/B 显示提示无效，契约仍然可以用于进度监控/恢复（不依赖语言），CHUNK-SERVO 仍然有效；这时把工程转到“进度头 + 恢复库”，而不是硬调提示。

## 5. 本轮一句话押注

**当前最值得押注的是 CSK-RUBRIC：把官方 94 个评分步骤编译成可执行的常识契约，用同一份契约驱动提示编译、演示对齐、进度/撤销监控和常识回放——在不增加在线模型的前提下，把“第一步就抓错/做到一半被拆掉”变成可检测、可恢复的子目标。**

# 第 13 轮产物 · CSK-RUBRIC 技术报告与持续迭代创新点清单

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（unibot.unitree.com；G1 + Dex1；32 项桌面任务；通才单模型赛道；选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「CSK-RUBRIC」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是在它们之上补一层**任务语义/程序层**。

## 0. 结论与边界

### 0.1 一句话结论

官方 32 个任务页公开了 **94 个评分步骤**、每步分值和泛化说明；把这 94 步离线编译成**带前置条件、效果、撤销边、物体角色、恢复策略的任务契约图**，再用同一份契约驱动**子目标提示、演示对齐、进度头、撤销检测、常识回放、步骤分投资组合**，可以在不增加在线学习模型的前提下，把「第一步就抓错 / 做到一半被人拆掉」从不可观测的语义失败变成可检测、可恢复的子目标。第 12 轮 CHUNK-SERVO 负责最后 3 厘米；本轮 CSK-RUBRIC 负责第一个 3 秒。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| **A** | 官方文档、提交模板、数据集元数据、排行榜 JSON、官方仓库代码直接核实 | 32 任务 / 94 步、API v2、33,276 eps、WLA `instruction` 接口 |
| **B** | 我们在公开数据/网页上做的可复现分析 | rubric 分值统计、部分得分上限、榜单 `step~success` 回归 |
| **C** | 设计假设，需 G0–G9 验证 | 子目标提示 +5pp、进度头撤销检测延迟 <1s、常识回放不掉点 |

### 0.3 本轮不做什么

- 不从零训 VLA/World Model；官方 WLA 已开源 6B 基座。
- 不做完整 sim-to-real 策略训练；仿真/增强只做训练数据和控制器风洞。
- 不做第二个在线学习模型/独立检测器/独立 VLM；进度头与动作头共享同一个 checkpoint。
- 不做 32 个任务各一个策略；规则禁止且不泛化。
- 不做 6D 物体位姿网络；透明/变形/反光不可靠，用角色、相对目标、契约证据。
- 不做力/触觉闭环；API 没有。
- 不做 30Hz 广域网伺服；用 5 步 chunk（第 12 轮）。
- 不把预览榜单的任务排名当实测难度表；已证伪。
- 不把旧 API 的 `data_keys` / `obs_chunk_size` 写进方案；当前是 `obs_delta_indices` / `image_resize` / `action_chunk_size`。
- 不假设「开源模型越多越好」；线上只跑一个 checkpoint。

### 1.2 提交 API（A）

当前提交模板 README（commit `edd0a1c9`，2026-08-21，README 标注 “version 2, support observation-based frame-skipping stacking, image scaling…”；2026-10-31 复核）：

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640** |
| 本体 | 双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str` |

| 观测堆叠 | `metadata.obs_delta_indices`：按观测键给帧偏移列表（如 `{"cam_left_high": [0,-1,-2], "state": [0,-1]}`）；`image_resize` 指定缩放 |
| token | `metadata.token` 握手校验一次；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile** |
| 监控 | 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分 |

**关键推论**：`action_chunk_size=30`、控制频率 30Hz 时，一次 `get_action` 之后有 **1 秒开环执行**；chunk 内没有新观测，也没有打断机制。契约监视器只能在 chunk 边界看到新观测；因此进度/撤销检测的延迟下限是“当前 chunk 剩余时间 + RTT”，不是 0。控制频率未在 README 中写死；本报告默认 30Hz，必须在单任务通道实测。

## 2. 问题形式化

### 2.1 记号

- 任务 $t \in \{1,\dots,32\}$，官方评分步骤 $g_{t,1},\dots,g_{t,n_t}$，权重 $w_{t,i}$，$\sum_i w_{t,i}=100$。
- 一次 trial 的轨迹 $\tau$；$R_{t,i}(\tau)\in\{0,1\}$ 表示是否达成第 $i$ 步；步骤分 $S_t(\tau)=\sum_i w_{t,i} R_{t,i}(\tau)$；成功 $Y_t(\tau)=R_{t,n_t}(\tau)$。
- 总平均成功率 $\bar Y = \frac{1}{32}\sum_t \hat P(Y_t=1)$；总平均步骤分 $\bar S = \frac{1}{32}\sum_t \mathbb E[S_t]$。
- 契约 $C_t=(\mathcal R_t,\mathcal G_t,E_t,U_t,\mathcal E_t,\mathcal Q_t)$：角色、子目标、正常边、撤销边、证据、恢复策略。

### 2.2 rubric 期望步骤分

对任务 $t$，令 $q_{t,i}=P(R_{t,i}=1)$。若步骤基本单调（做到 $i$ 通常意味着做到 $i-1$），则：

$$\mathbb E[S_t]=\sum_{i=1}^{n_t} w_{t,i} q_{t,i}, \qquad P(Y_t=1)=q_{t,n_t}.$$

若把“最后一步失败”记为 $q_{t,n_t}=0$，则步骤分上限为：

$$S_t^{\text{partial}}=\sum_{i=1}^{n_t-1} w_{t,i}=100-w_{t,n_t}.$$

这解释了为什么 balanced 任务的 tie-break 价值更高：$w_{t,n_t}$ 越小，失败时保留的步骤分越多。对 `50/50` 任务，最后一步失败只剩 50 分；对 `20×5` 任务，最后一步失败仍有 80 分。

**工程含义**：若预算有限，先修 $w_{t,n_t}$ 大的任务的最后一步（成功率和步骤分双收益）；对 balanced 任务，修早期步骤的收益更稳（即使最终失败也能拿分）。这就是 §8 的“步骤分投资组合”。

### 2.3 人为干扰是一个带撤销算子的 MDP

把评测建模为 $M=(S,A,P,r,\gamma)$，人为干扰在随机时刻施加操作 $u\in U$：

- $u_{\text{move}}$：移动目标/受器；
- $u_{\text{undo}}$：把已完成子目标的效果撤销（拧回盖子、翻开毛巾、拉开拉链）；
- $u_{\text{remove}}$：移除目标（拿走锁）；
- $u_{\text{add}}$：增加前置条件（另一头也插上）；
- $u_{\text{reset}}$：把物体放回起点（传送带）；
- $u_{\text{move-after-grasp}}$：抓取后移动受器/底座。

普通 VLA 的策略 $\pi(a\mid o)$ 只看到当前观测，不知道“进度被撤销”。契约监视器维护一个进度信念 $b_t(i)=P(\text{当前处于子目标 }i\mid o_{1:t},a_{1:t})$，并在 $b_t(j)<b_t(i)$ 且存在撤销边 $i\to j$ 时触发恢复。**这是把“语义失败”变成“状态估计失败”的关键一步。**

### 2.4 失败分类 F1–F5

| 失败类型 | 典型表现 | 对应泛化轴 | 本轮对策 |
|---|---|---|---|
| **F1 目标/角色错** | 抓了干扰物、抓了杯身而不是杯把、把“网口”当成“网线” | 未见物品、干扰物、背景 | 角色化提示 + 同 checkpoint 角色 grounding（watch） |
| **F2 子目标/顺序错** | 先倒药再拧盖、先拉拉链再对齐、长程任务漏步 | 位置、未见物品、长程 | 契约图 + 子目标提示 + 进度头 |
| **F3 前置条件/affordance 缺失** | 盖子没拧开就倒、插头方向反了、拉链头没咬合 | 未见物品、人为干扰 | 契约前置条件 + 证据门控 |
| **F4 进度被撤销/目标被移除** | 人把盖子拧回去、把毛巾翻开、把锁拿走、把食物放回起点 | 人为干扰（20% trials） | 进度回退检测 + 撤销边 + 恢复库 |
| **F5 最后 3 厘米接触误差** | 插不进、挂不上、叠不稳、拉链卡住 | 位置、人为干扰 | 第 12 轮 CHUNK-SERVO |

F1–F4 是“第一个 3 秒”的问题；F5 是“最后 3 厘米”的问题。两者共享同一个执行循环，但需要的信号不同：F5 需要几何/视觉伺服，F1–F4 需要**任务状态/语义**。

### 2.5 为什么“更大的 VLA”不自动解决 F1–F4

- Act2Answer：VLA 在动作微调后，富语义类别接近随机；VLM 基线高 20–40 分；VQA 联合训练有帮助。
- RoboSemanticBench：VLA 能抓起候选块，但选对语义答案接近/低于随机；“会抓”不等于“懂选哪个”。
- RoboSPA：最难层级所有模型 <25%，π0.5 22.3%；失败在目标 grounding、长程跟踪、记忆。
- ADAPT：真实环境有未指定的 affordance 约束；智能体需要感知物体状态、推断隐式前置条件；LoRA 微调的 VLM 做 affordance 后端比 GPT-4o 更好。

这些证据共同说明：**语义/程序能力不是“参数量”问题，而是“训练信号/接口”问题**。官方 rubric 正好提供了每任务的前置条件/子目标/分值，但没人把它变成训练/运行时信号。

### 2.6 为什么“场景泛化”不能只靠更多真实数据

- UMI-Bench 把 unseen 条件拆成 Factor A（物体/外观/类别/组合）和 Factor B（位置/布局/位姿/动力学），并分别报告 seen/unseen 与 generalization gap。
- ManipArena 的 10 次 trial 是分层设计：T1–T4 in-domain、T5–T8 视觉偏移、T9–T10 语义 OOD；例如勺子从不锈钢→儿童勺→黑色塑料勺。
- LIBERO-Plus 用 416 个干扰物和 target pose 扰动做渐进鲁棒性测试。
- RoboPRO 用 80 个双臂任务、16,000 条演示、不同干扰物密度做 perturbation-resilient 评测。
- RoboAug 用区域对比数据增强，把背景/干扰物/光照三因素下的成功率从 0.09→0.47、0.16→0.60、0.19→0.67（三个机器人）。

这些工作说明：**场景泛化可以被“分轴”测量和“分轴”增强**，不需要一个黑盒大模型硬吃。官方 5 轴正好给了分轴评测协议；我们可以用开源增强/回放分别打。

### 2.7 步骤分投资组合

设任务 $t$ 的修复成本 $c_t$，预期成功率增益 $\Delta q_{t,n_t}$，预期步骤分增益 $\Delta \mathbb E[S_t]$。在预算 $B$ 下：

$$\max_{\{x_t\in\{0,1\}\}} \sum_t x_t \left(\Delta q_{t,n_t}+\lambda \Delta \mathbb E[S_t]\right) \quad \text{s.t.}\quad \sum_t x_t c_t\le B,$$

其中 $\lambda$ 反映“成功率优先、步骤分 tie-break”的排名规则（先取大 $\lambda$ 保证成功率，再在成功率相同区间调小）。工程上不追求精确求解，只用它排序。

### 3.3 离线编译器

```text
输入：32 个 info.json + 任务语言 + 33k 演示 + 官方 generalization 说明
  │
  ├─ Step 1 解析 rubric：子目标、分值、难度、unseen/human 说明
  ├─ Step 2 LLM/VLM 起草契约：角色、affordance、前置条件、效果、undo 边
  │    （Qwen3-VL / UnifoLM-ER-1/Flow 均可，离线；输出 JSON Schema）
  ├─ Step 3 演示对齐：动作/状态 change-point + 腕部/头部视觉变化 + 关键帧描述
  │    → 每帧/每段一个子目标标签；动态规划保证单调；人工抽检 10%
  ├─ Step 4 人工审 94 个步骤：前置条件/效果/undo 边/恢复策略
  ├─ Step 5 生成提示变体：角色化、程序化、负约束、简短/详细两版
  ├─ Step 6 生成回放/增强数据：常识 VQA、背景/干扰物/外观增强
  └─ 输出：contracts/*.json、subgoal_labels.parquet、prompts/*.jsonl
```

关键点：

- **LLM 只离线用**：编译完就固化；线上不加载 LLM/VLM 教师，避免“第二个模型”。
- **94 个步骤是可控的标注预算**：1–2 人天可完成首轮人工审；比标 33k 条演示便宜得多。
- **演示对齐不是“再训一个模型”**：用确定性 change-point + 动态规划 + 离线 VLM 关键帧描述；输出是标签，不是在线策略。
- **契约可版本化**：每个任务一个 JSON，改动可 diff；单任务通道失败时可以定位到“哪条前置条件/undo 边写错了”。

### 3.4 演示对齐算法

目标：给每条成功演示的每一帧一个子目标标签 $z_t\in\{1,\dots,n\}$，满足单调、覆盖、时长合理。

```text
输入：演示 e 的帧特征 f_t（腕部/头部 ROI、EE 位姿、夹爪、关节），子目标数 n
1. 用确定性变化检测找候选边界：
   - 夹爪开合跳变、EE 速度/加速度峰值、腕部图像光流突变、接触段速度下降
2. 用离线 VLM 对关键帧生成“正在做什么”的描述，匹配子目标文本（余弦/关键词）
3. 动态规划：
   score(z_1..z_T) = sum_t sim(f_t, z_t) + λ1 * sum_t 1[z_t != z_{t-1}] 的边界奖励
                    - λ2 * 非法跳转惩罚 - λ3 * 子目标时长偏离先验惩罚
   约束：z_t 单调不减；每个子目标至少 L_min 帧；首尾覆盖
4. 输出标签 + 置信度；低置信度片段交人工
5. 人工抽检 10%；若某子目标对齐失败率 >20%，回到 Step 2 修契约
```

为什么不用“训一个阶段分类器再标”：那会引入额外模型和循环依赖；这里先用确定性信号 + 离线 VLM，标签一次生成，后续进度头只学这个标签。

### 3.5 提示编译器

WLA server 支持逐请求 `instruction`，所以不需要重训 VLM 就能注入提示。模板：

```text
Task: Plug the Ethernet cable into the network port.
Current subgoal 3/3 (40 pts): Insert the connector into the port opening.
Object roles: target = cable with connector; receptacle = port with opening.
Preconditions: connector aligned with opening; cable held; port stabilized.
Previous subgoal: port stabilized.
If the scene changed, re-localize the port before inserting.
Do not grasp the distractor cable.
```

四个变体：

1. **raw**：只用官方任务语言（基线）。
2. **short**：`Current subgoal i/n: ...`。
3. **role**：把实例描述换成角色/affordance（针对未见物品）。
4. **negative**：明确“不要抓干扰物/不要抓杯身”（针对干扰物）。

所有变体离线生成、人工审；在线只做字符串查表，CPU 开销可忽略。单任务通道先做 A/B，再决定是否全量。

### 3.6 人工审协议

- 每个契约由 1 名标注者起草、1 名复核；分歧用“是否可观测/是否影响步骤分”裁决。
- 审 5 项：角色是否覆盖所有官方物体；前置条件是否必要且可观测；效果是否对应评分点；undo 边是否覆盖官方 human 说明；恢复策略是否可执行。
- 记录“契约置信度” 0–2；低置信度任务在正式评测前用单任务通道验证，不盲投。

### 4.2 进度头 CSK-PROGRESS

在 WLA 的 action model 隐状态 $h_t$ 上接一个小的分类头：

$$p_\theta(z_t=i\mid o_{\le t})=\operatorname{softmax}(W_p h_t+b_p)_i,\qquad i=1,\dots,n_t.$$

- 训练：交叉熵 + 标签平滑；与动作损失联合训练，权重 $\lambda_p$（先 0.1–0.3）。
- 输出：`p(subgoal | obs)`，以及熵 $H_t=-\sum_i p_i\log p_i$。
- 在线：
  - `expected_i` 来自契约；`pred_i = argmax p`。
  - 若 `pred_i < max_reached` 连续 K 帧（默认 K=3），且契约有 `undo_edge(max_reached -> pred_i)`，判定**进度回退**，触发恢复。
  - 若熵 $H_t>\theta_H$，判定**语义不确定**，触发“更详细的子目标提示/重定位/安全 hold”。
- 为什么比几何编辑检测好：它直接学“任务处于哪个子目标”，不需要手工定义“场景动了但不是我动的”；人为撤销、目标移除、抓取后移动受器都可以表现为进度分布变化。
- 风险：进度头可能过拟合 canonical 场景；用场景增强 + 温度校准 + 契约证据交叉验证。

### 4.3 契约监视器状态机

```python
class ContractMonitor:
    def __init__(self, contract, progress_head, chunk_size, k=3, h_th=1.0):
        self.c = contract
        self.head = progress_head
        self.chunk = chunk_size
        self.k = k
        self.h_th = h_th
        self.max_reached = 0          # 已确认达到的最远子目标
        self.pending = 0              # 连续回退计数
        self.last_prompt = None

    def on_observation(self, obs):
        p = self.head(obs)            # 与动作头同一次 forward
        i = argmax(p)
        h = entropy(p)
        # 1) 语义不确定：不切换子目标，只加提示/重定位
        if h > self.h_th:
            return Action.RETRY_WITH_DETAILED_PROMPT
        # 2) 进度回退：只在有 undo 边时触发
        if i < self.max_reached:
            self.pending += 1
            if self.pending >= self.k and self.has_undo_edge(self.max_reached, i):
                return Action.RECOVER(to=i)
        else:
            self.pending = 0
        # 3) 正常推进：只有证据满足才更新 max_reached
        if i == self.max_reached + 1 and self.evidence_ok(i, obs):
            self.max_reached = i
        # 4) 完成
        if self.max_reached == len(self.c.subgoals) - 1:
            return Action.DONE
        return Action.CONTINUE

    def prompt(self):
        i = self.max_reached
        return self.c.prompts[i]      # 离线生成的查表字符串
```

注意：

- **只在 chunk 边界更新**：`on_observation` 每个 `get_action` 调用一次；chunk 内没有新观测。
- **证据门控**：`evidence_ok` 用确定性信号（夹爪开合、EE 位移、ROI 变化、插入深度）或进度头置信度；不满足就不推进，避免“假完成”。
- **安全回退**：`RECOVER` 不是直接重规划，而是“退回子目标 $i$ 的提示 + 恢复脚本 + 限速”；若连续失败 2 次，进入 safe hold/放弃该 trial。

### 4.4 恢复库

| 场景 | 检测 | 恢复 |
|---|---|---|
| 目标/受器被移动 | ROI 跳变、相对位姿变化 | 重定位目标/受器；重新检索 DG-KEYFRAME；再执行当前子目标 |
| 已完成步骤被撤销 | 进度头回退 + undo 边 | 把 `max_reached` 退到 `to`；用该子目标提示重做；必要时先撤销后续效果 |
| 目标被移除 | 进度头熵高 + ROI 丢失 | 安全 hold/搜索；若超时，放弃该 trial（避免碰撞） |
| 增加前置条件 | 语言/场景出现新物体 | 重新编译子目标序列；若无法完成，安全失败 |
| 抓取后移动底座 | 夹爪持物 + 底座 ROI 跳变 | 保持夹持；重估底座；重新放置 |
| 最后 3 厘米失败 | CHUNK-SERVO 误差/滞止 | 法向缩幅、重对齐、重试；最多 2 次 |

恢复库是**确定性脚本 + 提示**，不是学习模型；每个脚本有最大重试次数和速度限制，避免“恢复”变成“撞桌子”。

### 4.5 与 CHUNK-SERVO 集成

第 12 轮 CHUNK-SERVO 的执行循环：

1. WLA 输出 30 步规划；
2. 切成 6 个 5 步执行块；
3. 每个执行块用腕部/头部视觉做一次闭环修正；
4. 目标来自 DG-KEYFRAME 检索的“受器-夹爪相对位姿”；
5. 接触段法向缩幅。

本轮在其外层加：

- **子目标提示**：每个执行块开始时，用 `monitor.prompt()` 选择当前子目标提示；WLA 重新规划 30 步，但只执行前 5 步。
- **进度门控**：若 `monitor` 判定回退，跳过当前块，进入恢复脚本。
- **证据记录**：每个块的证据写入 per-trial log，供离线分析和单任务通道复盘。

两层的分工：

| 层 | 频率 | 信号 | 解决 |
|---|---|---|---|
| CSK-RUBRIC | 每 5 步/chunk 边界 | 子目标、进度、撤销边、角色 | F1–F4（第一个 3 秒） |
| CHUNK-SERVO | 每 5 步执行块内 | 视觉伺服、相对位姿、接触 | F5（最后 3 厘米） |

### 4.6 WLA adapter（54D→21D）

```python
def wla_to_challenge(action54, obs):
    # 1) 取 WLA 的绝对 EE xyz+rpy、gripper、lower_body、base_command、pivot
    left_ee = action54["left_ee_pose"]       # xyz+rpy, base
    right_ee = action54["right_ee_pose"]
    left_g = action54["left_gripper"]
    right_g = action54["right_gripper"]
    pivot = action54["pivot"]                # 7D
    # 2) 挑战赛 ee 动作：2×6 绝对 EE + 2×1 gripper + 7 pivot = 21D
    return {
        "left_ee_pose_gripper_base": left_ee,     # 6
        "right_ee_pose_gripper_base": right_ee,   # 6
        "left_gripper": left_g,                    # 1
        "right_gripper": right_g,                  # 1
        "pivot": pivot,                            # 7
    }
```

$$T_{\text{abs}}^{\text{new}}=T_{\text{abs}}^{\text{cur}}\cdot T_{\text{rel}}^{\text{pred}}.$$

## 5. 训练配方

### 5.1 数据

| 数据 | 用途 | 规模 |
|---|---|---|
| 官方 33,276 条成功演示 | 动作 BC、子目标标签 | 169.28 h |
| 契约/子目标标签 | 进度头、rubric 加权 | 94 步 × 33k 帧级标签 |
| 常识回放 | 防语义遗忘 | 5–10% 混采 |
| 场景增强 | 背景/干扰物/外观/位置 | 按需生成 |
| 单任务通道 | A/B 验证 | 不计分 |

划分：按 **episode/session/物体/背景** 分组，相邻帧不跨 split；避免同一 episode 的相邻帧泄漏到验证集。官方 32 个数据集分开，留出 2–3 个任务做“未见任务”泛化检查（不作为正式评测依据）。

### 5.2 Rubric-weighted loss

$$\mathcal L = \sum_{t}\sum_{i\in \text{subgoals}(t)} w_{t,i}\,\ell_{\text{action}}(t,i) + \lambda_p \mathcal L_{\text{progress}} + \lambda_c \mathcal L_{\text{replay}}$$

- $w_{t,i}$ 先按官方分值归一化（如 30/30/40 → 0.3/0.3/0.4），再做温度平滑 $w_{t,i}^{1/\tau}$，避免最后一步过拟合。
- **子目标平衡采样**：对稀有/难子目标（拉链、锁、针管、开盖）过采样；对简单子目标设上限。
- **进度损失**：只在有可靠标签的帧上算；标签噪声用 label smoothing + 置信度加权。
- **回放损失**：语言建模/子目标分类；与动作损失联合，避免灾难性遗忘。

### 5.3 CSK-REPLAY（常识回放）

Act2Answer 的结论是 VQA 联合训练与知识保留相关。三个层级：

| 方案 | 做什么 | 成本 | 风险 |
|---|---|---|---|
| **REPLAY-A** | 冻结 VLM，在 action head 上加辅助子目标/角色分类损失 | 低 | 只影响 action head，语义容量有限 |
| **REPLAY-L（推荐）** | 对 VLM 做 LoRA，混入 5–10% 常识/具身推理数据，语言建模 + 动作联合 | 中 | 需显存/调参；可能伤动作 |
| **REPLAY-D** | 用更大开源 VLM/ER-1 离线蒸馏到 WLA 的 VLM LoRA | 中高 | 蒸馏信号难设计；需确认合规 |

常识数据来源：ERQA-Plus、Act2Answer 风格二选题、RoboSemanticBench 风格候选选择、官方 rubric 生成的“前置条件/顺序/角色”问答。**只离线训练，不线上调用。**

### 5.4 场景课程

按五轴从易到难：

1. **背景替换**：真实前景 mask + 其他桌面纹理；
2. **干扰物 copy-paste**：从其他 episode/开放数据取物体，放在工作空间边缘→路径附近；
3. **目标外观替换**：颜色/材质/尺寸；用分割 mask 做 compositing；
4. **位置偏移**：目标/受器平移/旋转；配合目标相对表示；
5. **遮挡/人手进入/目标移除**：合成遮挡 + 契约恢复；不追求照片级真实。

增强数据只用于训练，线上仍是一个 checkpoint。先用开源增强/分割工具（RoboAug 思路、SAM 离线）做第一版，再在单任务通道验证是否真涨点；不假设生成数据一定有用。

### 5.5 LoRA-SOUP

如果做了多个 LoRA（不同任务组/增强强度/回放比例），用权重平均（SOUP）合并，而不是线上多模型：

- 只合并**同一基座、同一架构**的 LoRA；
- 在验证集上选合并系数；
- 合并后仍是一个 checkpoint；合规模式 C3；
- 风险：不同 LoRA 的秩/缩放不一致会掉点；先在单任务通道验证。

### 5.6 计算与超参（初始值）

| 项 | 初始值 | 说明 |
|---|---|---|
| 基座 | UnifoLM-WLA-1.0-Base | Apache 2.0 |
| 微调 | LoRA r=16–32, α=32 | 单卡 24GB 可跑 |
| batch | 8–16（梯度累积） | 视显存 |
| lr | 1e-4（LoRA）/ 1e-5（head） | 先小后大 |

## 6. 创新点清单（living）

> 说明：每个点都按「动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险」写。状态：**core**（本轮主推）、**retain**（保留前轮）、**watch**（观察，不主推）、**pruned**（剪枝）。

### I1. CSK-RUBRIC：官方评分表 → 可执行常识契约（core）

- **动机**：官方 94 个评分步骤是免费的程序规范；现有 VLA 只吃任务语言，不知道前置条件/撤销/恢复。
- **差异**：不是“再写一段 prompt”，而是把 rubric 编译成带 `preconditions/effects/undo_edges/recovery` 的 JSON 契约；契约驱动提示、进度、恢复、回放、投资组合。
- **可行性**：32 个 `info.json` 已公开；94 步人工审 1–2 人天；LLM/VLM 离线起草；JSON Schema 可校验。
- **资源**：1 名标注 + 1 名复核；1 张 GPU 做离线 VLM；无需真机即可完成首版。
- **步骤**：抓 32 个 info.json → 起草 32 个契约 → 演示对齐 → 人工审 → 单任务通道验证 → 版本化发布。
- **风险**：契约写错会误导监视器；用“证据可观测/影响步骤分”两条裁决；低置信度任务不盲投。
- **验证**：G0（契约一致性）、G1（子目标对齐）、G2（提示 A/B）。

### I2. 子目标提示编译器（core）

- **动机**：WLA server 支持逐请求 `instruction`；官方任务语言是整段任务，不是“当前该做什么”。
- **差异**：把契约的当前子目标/前置条件/角色/负约束编译成短提示；raw/short/role/negative 四变体 A/B。
- **可行性**：零样本即可试；不需要重训 VLM；CPU 查表。
- **资源**：离线生成 + 人工审；单任务通道 5 任务 × 5 次 × 4 变体。
- **步骤**：生成变体 → 单任务 A/B → 选 1–2 个变体 → 全量。
- **风险**：WLA 可能对提示不敏感；若 A/B 无效，退回“契约只做监控/恢复”，不硬调。
- **验证**：G2。

### I3. CSK-PROGRESS：同 checkpoint 子目标进度头（core）

- **动机**：现有 VLA 没有“做到哪”的输出；开环 chunk 内无法知道进度。
- **差异**：在 WLA action model 隐状态上加小分类头，与动作头共享 checkpoint；不是第二个模型。
- **可行性**：子目标标签可由 §3.4 自动生成；2–5 类小头，训练成本低；推理 <1ms。
- **资源**：33k 演示帧级标签；单卡微调；无额外真机。
- **步骤**：对齐标签 → 加头联合训练 → 校准（temperature scaling）→ 单任务通道测准确率/延迟。
- **风险**：只见过成功演示，可能不会识别“撤销”；用状态回退先验 + 合成 undo + 证据交叉验证；若失败，退回确定性证据。
- **验证**：G3（离线准确率/校准）、G4（在线撤销检测）。

### I4. CSK-REGRESS：进度回退/人为撤销检测与恢复（core）

- **动机**：官方 13 个任务包含撤销/移除/动态重置/增加前置条件/抓取后移动受器；视觉伺服只看到“物体动了”，不知道“进度被撤销”。
- **差异**：把“编辑检测”升级为“契约撤销边 + 进度回退 + 恢复库”；不是简单的场景变化检测。
- **可行性**：进度头 + 确定性证据 + 契约状态机；恢复脚本可离线写；单任务通道可测。
- **资源**：每个 undo 边 1 个恢复脚本；13 个任务优先；人工写 + 仿真风洞。
- **步骤**：枚举 undo 边 → 写恢复脚本 → 合成/人工演示测试 → 单任务通道测恢复成功率/误触发。
- **风险**：误触发会打断正常执行；用 K 帧确认、证据门控、最大重试；误触发率 >5% 就收紧。
- **验证**：G4、G5。

### I5. Rubric-weighted loss + 子目标平衡采样（core）

- **动机**：官方分值不均；最后一步 40–50 分的任务占 25/32；普通 BC 对所有帧等权，浪费步骤分信号。
- **差异**：按官方步骤分值加权动作损失；对稀有子目标过采样；温度平滑防过拟合。
- **可行性**：只需标签 + 损失改动；不增加模型。
- **资源**：无额外数据；训练调参。
- **步骤**：实现加权 → 小规模消融 → 单任务通道验证 → 全量。
- **风险**：最后一步过拟合伤早期步骤；用验证集/单任务通道监控；温度平滑。
- **验证**：G6（离线/单任务消融）。

### I6. CSK-REPLAY：常识回放（core/watch）

- **动机**：Act2Answer/RoboSemanticBench 表明动作微调会洗掉语义；官方 rubric 需要常识（角色、前置条件、顺序）。
- **差异**：不是线上加 VLM，而是训练时混入 5–10% 常识/具身推理数据；REPLAY-A/L/D 三档。
- **可行性**：WLA 支持 LoRA；ERQA-Plus/Act2Answer/RoboSemanticBench 公开；单卡可跑。
- **资源**：1 张 GPU；常识数据准备；LoRA 训练。
- **步骤**：先 REPLAY-A（便宜）→ 若语义指标掉点再 REPLAY-L → 单任务通道确认动作不掉。
- **风险**：回放数据分布不匹配会伤动作；先 5%，监控动作验证损失；REPLAY-D 需合规确认。
- **验证**：G7（常识诊断 + 动作不掉点）。

### I7. 场景/角色课程（core）

- **动机**：官方 5 轴泛化；未见物品/干扰物/背景各 2 次；33k 数据是 canonical 场景。
- **差异**：按五轴分轴增强 + 角色化提示；不是“更多真实数据”。
- **可行性**：RoboAug/SAM/开源分割可离线做；增强只进训练。
- **资源**：离线增强管线；GPU/CPU；单任务通道验证。
- **步骤**：背景 → 干扰物 → 外观 → 位置 → 遮挡/人手；每步单任务 A/B，不涨就回退。
- **风险**：合成数据不真实/泄漏；按 session/物体/背景分组划分；只保留验证有效的增强。
- **验证**：G8（分轴泛化）。

### I8. Rubric 步骤分投资组合（core）

- **动机**：排名先成功率、再步骤分；25 final-heavy + 7 balanced；预算有限。
- **差异**：用官方分值算 $S^{\text{partial}}$ 和期望步骤分，按 `Δscore/cost` 排序；不是拍脑袋选任务。
- **可行性**：rubric 已公开；单任务通道可测；无需额外模型。
- **资源**：分析脚本 + 单任务通道。
- **步骤**：算每个任务的 final 权重/partial/难度 → 选 5 个代表任务 → A/B → 全量。
- **风险**：预览榜单/任务排名误导；只用 rubric + 单任务通道，不用榜单当 ground truth。
- **验证**：G9（提交策略复盘）。

### I9. CHUNK-SERVO（retain，第 12 轮）

- **动机**：30 步开环 chunk 在最后 3 厘米没有反馈。
- **差异**：30 步规划 + 5 步视觉伺服；DG-KEYFRAME 相对目标；数字孪生只标定。
- **可行性**：已在第 12 轮详细设计；CPU 伺服；单任务通道可测。
- **资源**：腕部标定、演示检索索引、仿真风洞。
- **步骤**：保留第 12 轮 G0–G7；本轮只加“子目标提示/进度门控”接口。
- **风险**：RTT/增益/外参不稳；用 5 步 chunk、RTT 测量、失败回退 8–10 步。
- **验证**：第 12 轮 G2/G7 + 本轮 G5。

### I10. DG-KEYFRAME（retain，第 12 轮）

- **动机**：绝对目标位姿对物体移动不鲁棒；演示里有大量“受器-夹爪”相对关系。
- **差异**：从 33k 成功演示检索相对位姿/腕部目标图；任务/阶段/相对位姿过滤；top-k 重打分。
- **可行性**：离线建索引；在线检索 <10ms；无需训练。
- **资源**：演示关键帧特征库；CPU。
- **步骤**：保留第 12 轮；本轮把“阶段”换成契约子目标，提高检索精度。
- **风险**：检索 mismatch；置信度低回退 VLA；透明/反光只对刚体启用。
- **验证**：第 12 轮 G1/G3 + 本轮 G5。

### I11. GEO-RESIDUAL（retain，第 11 轮）

- **动机**：接触/编辑事件是低维残差，不需要大模型重训。
- **差异**：动作条件化残差 + 相位化 BC；只在高价值接触段启用。
- **可行性**：第 11 轮已设计；与 CHUNK-SERVO 共用接触信号。
- **资源**：接触/编辑标签；轻量残差头。
- **步骤**：保留；本轮用契约证据替代部分手工编辑标签。
- **风险**：残差过拟合/误触发；限幅/限速/最大重试。
- **验证**：第 11 轮门 + 本轮 G5。

### I12. 动作方差/测试时增强（watch）

- **动机**：WLA 是扩散模型；多次采样方差可作为“不确定性”信号。
- **差异**：同 checkpoint 多次采样，比较动作方差；高方差时降速/重试/切换提示。
- **可行性**：只增加推理次数；不需要新模型；但延迟翻倍。
- **资源**：GPU 推理预算；单任务通道。
- **步骤**：先离线测方差-成功率相关性；若强，再在线用于门控。
- **风险**：延迟/吞吐；方差不一定校准；暂不主推。
- **验证**：G3/G5 的附加分析。

### I13. LoRA-SOUP（watch）

- **动机**：多个 LoRA（任务组/增强/回放）可能互补；线上不能多模型。
- **差异**：权重平均合并成一个 checkpoint；合规 C3。
- **可行性**：同基座/同架构；单卡；已有开源工具。
- **资源**：多 LoRA 训练；验证集选系数。
- **步骤**：先训 2–3 个 LoRA → 验证集网格搜索 → 合并 → 单任务通道。
- **风险**：秩/缩放不一致掉点；合并后需完整回归。
- **验证**：G6/G8。

### I14. 契约条件化动作专家（watch）

- **动机**：把子目标 one-hot/文本嵌入注入 action head，可能比纯提示更强。
- **差异**：在 action expert 上加 FiLM/AdaLN 条件；仍是同一 checkpoint。
- **可行性**：需要改 WLA 结构；训练成本中等；有破坏基座风险。
- **资源**：GPU 微调；消融。
- **步骤**：先做小规模 LoRA + 条件注入；若单任务通道显著，再扩大。
- **风险**：过拟合任务/子目标；与提示重复；暂不主推。
- **验证**：G6。

### I15. 腕部标定/头双目深度（retain）

- **动机**：腕部无内参；头双目有基线/焦距，可做局部深度。
- **差异**：一次性棋盘格标定 + D435 先验 + 头双目 PBVS 兜底；不是 6D 位姿网络。
- **可行性**：第 12 轮已设计；单任务通道可测。
- **资源**：标定板；每机器人一次。
- **步骤**：标定 → 重投影检查 → 伺服启用条件。
- **风险**：标定漂移/换机器人；误差大关伺服。
- **验证**：第 12 轮 G0/G2。

### I16. 开源契约包（ecosystem，core）

- **动机**：开源生态缺“官方 rubric → 可执行契约”的工具；这是可复用的社区贡献。
- **差异**：发布 32 个契约 JSON + 编译器 + 校验器 + 演示对齐脚本（Apache-2.0）；不发布模型权重。
- **可行性**：纯离线工具；不影响比赛合规。
- **资源**：文档/测试/CI；1–2 周。
- **步骤**：整理契约 → 写 Schema/校验 → 示例 → 发布。
- **风险**：官方 rubric 版权/引用；只发布“结构化描述 + 来源链接”，不复制长段官方文本。
- **验证**：社区反馈 + 单任务通道。

| 想法 | 为什么剪 |

## 7. 实验设计

### 7.1 门 G0–G9

| 门 | 假设 | 方法 | 通过标准 | 失败回退 |
|---|---|---|---|---|
| **G0 契约一致性** | 32 个契约覆盖 94 步、角色/证据/undo 边完整 | JSON Schema + 人工审 + 自动检查 | 100% 步骤有权重；≥90% 证据可观测；≥13 个任务有人为干扰恢复策略 | 修契约，不进训练 |
| **G1 子目标对齐** | 自动对齐与人工抽检一致 | 10% 抽检；混淆矩阵 | 帧级准确率 ≥85%；相邻子目标混淆 ≤15% | 改变化检测/加人工 |
| **G2 提示 A/B** | 子目标提示比 raw 好 | 单任务 5×5×4 变体 | ≥3/5 任务步骤分 +5 或成功率 +10pp | 退回契约监控，不硬调 |
| **G3 进度头** | 离线准确率/校准足够 | 留出任务/背景分组 | 准确率 ≥80%；ECE ≤0.1 | 加数据/简化类别 |
| **G4 撤销检测** | 进度回退可检测 | 合成 undo + 人工演示 | 延迟 ≤1 chunk；误触发 ≤5% | 收紧 K/证据门控 |
| **G5 恢复** | 恢复脚本能救回部分 trial | 单任务通道 | 恢复成功率 ≥50%；碰撞 0 | 限速/放弃 |
| **G6 训练消融** | rubric 加权/回放/增强有增益 | 离线 + 单任务 | 至少 2/3 消融 +3pp | 剪掉无效项 |
| **G7 常识回放** | 回放不掉动作、涨语义 | 常识诊断 + 动作验证 | 语义 +5pp；动作 −1pp 内 | 降比例/改 REPLAY-A |
| **G8 场景泛化** | 增强在未见轴涨点 | 分轴留出 | 至少 2 轴 +5pp | 只保留有效增强 |
| **G9 提交策略** | 步骤分投资组合有效 | 正式评测/复盘 | 成功率或步骤分提升；无回归 | 回退基线 |

### 7.2 离线实验（不需要真机）

1. **契约覆盖**：32 个 JSON 对 94 个步骤；检查每个步骤有 `weight/text/preconditions/effects/evidence/undo_if/recovery`。
2. **演示对齐**：在 3 个任务（HangCup、PlugInEthernet、FoldTowel）上人工标 50 条，测帧级准确率/边界误差。
3. **进度头**：留出 2 个任务做 unseen-task；留出背景/物体做 OOD；测准确率、ECE、混淆矩阵。
4. **撤销检测**：用“成功演示的前段帧 + 后段帧倒放/合成”做 sanity check；再用单任务通道的人为干扰做真实测试。
5. **提示敏感性**：离线用 WLA 对同一观测不同提示算动作差异；若差异接近 0，提示路线降级。
6. **常识诊断**：ERQA-Plus/Act2Answer 风格小集；测 REPLAY 前后语义分数。
7. **增强有效性**：在验证集上分轴测；不在训练集上报。

### 7.3 单任务 A/B 协议

**任务选择（5 个代表）**：

| 任务 | 为什么选 | 关注 |
|---|---|---|
| PlugInEthernet（T26） | 插入，final-heavy，30/30/40 | F5 + F3 |
| ZipUp（T19） | 拉链，human-undo，50/50 | F4 + F5 |
| PourOutMedicine（T14） | 开盖+倒，human-undo，50/50 | F3 + F4 |
| StackBowls（T27） | 叠放，final-heavy，30/30/40 | F5 + F4 |
| FoldTowel（T16） | 5 步 balanced，防回归 | F2 + 步骤分 |

**协议**：

1. 每个任务 5 次 A/B：raw prompt vs CSK-RUBRIC（short/role/negative + 进度恢复）；同初始条件；随机化顺序。
2. 记录：成功、步骤分、耗时、p99、恢复次数、误触发、碰撞/安全事件。
3. 通过：≥3/5 任务步骤分 +5 或成功率 +10pp；FoldTowel 不回归 >5pp；p99 不升 >20%。
4. 再扫 `action_chunk_size ∈ {5,8,30}` 和提示变体；选最佳折中。
5. 最后才跑 32×10 正式评测。

### 7.4 指标与统计

- **主指标**：32 任务平均成功率；平均步骤分。
- **次指标**：每轴（位置/干扰物/背景/未见物品/人为干扰）成功率；final-heavy vs balanced；恢复成功率；误触发率；p50/p99 延迟。
- **统计**：
  - 单任务 5 次 A/B 的噪声很大；用配对 bootstrap + McNemar（成功/失败）或 Wilcoxon（步骤分）。
  - 32×10=320 trials 的二项标准误约 $\sqrt{0.25/320}\approx2.8$pp（最坏情况）；实际每任务 10 次，任务间相关，SE 可能更大；不要用 1–2pp 的差异宣称有效。
  - 多任务/多指标比较用 Holm/BH 校正；预注册主指标，避免 p-hacking。
  - 正式评测只能提交有限次数；单任务通道用于筛候选，正式评测用于确认。

### 7.5 消融

| 消融 | 目的 |
|---|---|
| raw vs short vs role vs negative | 提示贡献 |
| 无进度头 vs 进度头（不恢复） | 监控贡献 |
| 进度头 + 恢复 vs 只恢复 | 撤销检测贡献 |
| 无 rubric 加权 vs 加权 | 步骤分贡献 |
| 无回放 vs REPLAY-A/L | 常识贡献 |
| 无增强 vs 分轴增强 | 泛化贡献 |
| 5 步 vs 8 步 vs 30 步 | 控制贡献（第 12 轮） |
| 无 CHUNK-SERVO vs 有 | 最后 3 厘米贡献 |

### 8.3 提交与安全

- 先交**安全基线**（WLA + CHUNK-SERVO，不带进度恢复），锁 tie-break；
- 再交 **CSK-RUBRIC 候选**（只加已验证的提示/恢复）；
- 每次提交前跑 5 任务单任务通道；任何碰撞/超时/端口错误一票否决；
- 端口 8765..8765+N-1 全开；`reset()` 隔离；token 每次带；日志脱敏；
- 失败回退：恢复连续失败 2 次 → safe hold/放弃；不硬撞。

## 9. 风险与合规

### 9.1 风险表

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 单模型解释 | 中 | 被判定第二个模型 | 线上只跑一个 checkpoint；契约/提示/伺服是确定性代码；C1/C2/C3 模式；提交材料写清 |
| 离线 LLM 编译被误解 | 低 | 合规争议 | 离线工具不参与测试；只发布结构化契约；保留人工审记录 |
| 提示无效 | 中 | G2 失败 | 契约仍可用于监控/恢复；不硬调提示 |
| 进度头不识别 undo | 高 | G4 失败 | 合成 undo + 证据门控 + 回退几何/夹爪信号 |
| 误触发恢复 | 中 | 打断正常执行 | K 帧确认、证据门控、最大重试、误触发率门 |
| 恢复碰撞 | 低 | 安全事件 | 限速/限幅/力限（若有）/safe hold |
| 增强数据不真实 | 中 | 掉点 | 分轴验证，不涨就回退 |
| 回放伤动作 | 中 | 动作退化 | 5% 起、监控动作验证、REPLAY-A 兜底 |
| 腕部无内参 | 高 | 伺服不准 | 棋盘格标定 + 头双目兜底 + 误差大关伺服 |
| RTT 高/抖动 | 中 | 伺服不稳 | 5 步 chunk、RTT 测量、回退 8–10 步 |
| 控制频率未知 | 高 | 时间预算错 | 单任务通道实测；按 30Hz 设计但留余量 |
| 榜单误导 | 高 | 选错任务 | 只用 rubric + 单任务通道；榜单只当预览 |
| 评测噪声 | 高 | 假阳性 | 配对 A/B、bootstrap、重复实验、预注册 |
| 数据泄漏 | 中 | 离线虚高 | 按 session/物体/背景分组；相邻帧不跨 split |
| 官方 rubric 变更 | 低 | 契约过期 | 版本化；提交前重抓；diff 检查 |

### 9.2 合规模式

- **C1 离线标注**：契约/子目标标签由离线 LLM/VLM + 人工生成，不进入测试时；最稳。
- **C2 确定性控制器**：提示查表、契约状态机、CHUNK-SERVO、恢复脚本；无学习权重；不是模型。
- **C3 同 checkpoint 特征**：进度头与动作头共享同一个 WLA checkpoint；一次 forward；不是第二个模型。
- **灰色地带**：LoRA-SOUP、离线蒸馏到 LoRA、多个 LoRA 合并；先邮件确认，默认不用于正式提交。

**提交材料建议**：一段“系统组成”说明 + 一个 checkpoint + 确定性代码清单 + 离线工具不参与测试的声明 + 单任务通道日志。避免“我们用了多个开源模型”这种容易被误判的表述。
