## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（传感器融合 → 评测给的是一台「标定过的多相机 + 本体感知」设备，基线只用了其中一部分）**

直觉：这场比赛的观测不是一个黑箱 RGB，而是一套**已经标定过的传感器组**：头戴双目（rectified）、双腕 eye-in-hand、双臂关节、base 系 ee 位姿、waist/legs。可基线只吃了 3 路图（左目 + 双腕），把右目扔了（F25）；而评测接口同时给左右 high（F20）。如果 H1 成立，**右目就是白送的 metric depth**。更关键的是，数据集 `camera_params` 已经把双目 K/畸变/R/T 和腕部彩色 K 都给了（F23）——这不是「要自己猜相机」的赛道，而是「标定已经给了，看你会不会用」。

真正没给的只有一块：**腕部相机相对末端的手眼变换 `T_ee_cam`**（H2）。这正是「手眼标定」要补的缺口。补上之后，腕部图像可以按当前 ee pose 反投影到 base 系，变成一个**不随手臂构型变化**的稳定 3D 观测；头部双目也可以按 `T_base_head` 反投影到 base 系；两者融合成「场景的 base 系几何」。而动作本来就是 base 系 ee 目标位姿（F21）——观测、几何、动作第一次在同一坐标系里。核心反直觉点：**泛化缺口的很大一部分不是「没见过新物体」，而是「模型在隐式地学正向运动学 + 相机外参」；手眼标定把这块隐式几何变成显式几何，模型就不用把容量浪费在像素→关节的坐标变换上。**

**灵感 2（手眼标定 → 标定的价值不在「算出一个矩阵」，而在「把移动相机变成稳定坐标系」）**

直觉：腕部相机是 eye-in-hand：同一个物体，手臂一换构型，像素位置就剧烈变化。端到端策略必须从数据里反推 `T_base_ee(t)·T_ee_cam`；数据效率低，外参一变就崩。手眼标定后，腕部像素 → base 系 3D 点云，头部双目也 → base 系 3D 点云，融合成「物体在机器人坐标系里的位置」。这直接对齐 5 条泛化轴：位置轴（base 系平移等变）、背景/光照轴（几何对纹理不敏感）、干扰物轴（3D 聚类 + 语言 grounding 分离目标）、未见物体轴（几何给形状/尺寸，I9 检索给语义先验）。更进一步，标定可以反过来当训练信号：**手眼一致性损失**（预测的 ee 运动应与腕部光流/头部深度一致），这样即使评测端外参与数据集有偏差，模型学到的也是「几何关系」而不是「死记一个矩阵」。核心反直觉点：**手眼标定不是部署前的一次性工程，而是一个可微/可自监督的几何正则项；它让「零样本泛化」从像素空间搬到 SE(3) 空间。**

**两者统一（观测侧结论）**：v1.1 的结论是「中期胜负手在数据引擎」；本轮补一句——**数据引擎决定「见过什么」，传感器融合决定「以什么坐标系看」；后者是乘性项，且官方已经把标定参数放在数据里，先手成本极低。**

## 2. 严谨定义（把直觉写成可检验的式子）

### 2.1 传感器融合

设传感器 `i=1..M` 在 `t` 时刻给出 `z_i(t)`，其到机器人 base 系 `B` 的变换为 `T_B^{S_i}(t)`，场景隐状态为 `x`（目标物体的 3D 位姿/关键点）。融合后验：

`p(x | z_1..z_M) ∝ p(x) ∏_i p(z_i | x, T_B^{S_i}(t))`

几何融合取 MAP / 最小重投影：

`x* = argmin_x Σ_i ρ( || π_i( (T_B^{S_i})^{-1} x ) - z_i ||^2_{Σ_i} ) + prior`

本赛题取 `x` =「目标物体关键点在 base 系的 3D 坐标 + 抓取朝向」；`z_i` = 4 路 RGB；`T_B^{S_i}` 由 2.2 标定。策略侧不显式求 `x*`，而是用可微编码器 `f(z_1..z_M, s)` 学到等价表示，训练时加几何辅助损失。

### 2.2 手眼标定

腕部相机 `C` 刚性固定在末端 `E` 上，则

`T_B^C(t) = T_B^E(t) · T_E^C`，记 `X := T_E^C` 为常量。

给定两个时刻 `t1,t2`，令

`A = T_B^E(t2) (T_B^E(t1))^{-1}`，`B = T_B^C(t2) (T_B^C(t1))^{-1}`，

则 `A X = X B`（经典 AX=XB）。若 `T_B^C(t)` 可由头部双目 + PnP/特征匹配估计，也可直接

`X = (T_B^E(t))^{-1} T_B^C(t)`

对多帧做 SE(3) 鲁棒平均（更简单、对异常帧鲁棒）。头部相机 `H` 同理：`T_B^H(t) = T_B^T(t) · T_T^H`，`T_B^T` 由 waist/躯干链给出，`T_T^H` 常量。

### 2.3 由本体感知恢复尺度

双目深度 `d = f·b / disparity`。若 `f`、`b` 未知或单位不确定，用已知 ee 位移作尺度锚：

`s* = argmin_s Σ_t || s·\hat{X}_t - (T_B^E(t) p_E + ...) ||^2`

数据集已给 K/R/T（F23），理论上可跳过；此式用于跨机器人/跨标定版本的鲁棒校验。

### 2.4 无力传感器的接触代理（sensor fusion 的第二用法）

设 `a_t` 为策略下发的 base 系目标 ee 位姿，`s_t` 为观测到的实际 ee 位姿，跟踪残差

`r_t = Log( T(a_t)^{-1} T(s_t) ) ∈ se(3)`

若 `action` 是「下一时刻目标」，则改用 `s_{t+1}` 并离线标定最优 lag `Δ`。自由空间 `r_t ≈ 0 + 噪声`；接触时环境施加 wrench `w_t`，柔性控制器近似 `r_t ≈ C w_t`。于是 `r_t` 是 `w_t` 的含噪线性观测。再融合腕部视觉接触证据 `v_t`（物体位移/形变/遮挡），得

`p(contact | r_t, v_t) ∝ p(r_t | contact) p(v_t | contact) p(contact)`

用途：I3 接触段触发、I5 恢复触发、I4 干预门控。可在示教数据上离线检验（action 与 state 的 ee pose 差）。

# UniBot-V1 参赛创新点清单（第 1 轮 v2.0：传感器融合 × 手眼标定）

> 检索日期：2026-11-27（本轮）；承接 v1.1（I1–I9，前序第 2 轮）。本轮新增 I10/I11，更新 I3/I4/I5/I6/I9 的输入表示与实验协议；清单只增改不重置。

## 0. 本轮结论（先看这三句）

1. **基线浪费了一路已标定的传感器**：Dex1 训练只用 `head_stereo_left + wrist_left + wrist_right`（F25），右目 `head_stereo_right` 在数据里、评测端也以 `cam_right_high` 提供（F20/H1），却未被利用。
2. **数据集已经把相机内参/双目外参给了**（F23），真正缺的是腕部 `T_ee_cam`——这正是手眼标定要补的、且可用示教数据自监督估计的一块。
3. **观测/几何/动作可以统一到 base 系**：ee pose 是 base 系（F20），动作也是 base 系目标位姿（F21）。把视觉 lift 到 base 系 3D，是把「零样本泛化」从像素空间搬到 SE(3) 空间的最短路径。

## 1. 新增事实与关键推断（与想法区 §0 对应）

**已核实（F20–F27）**：评测 4 路 RGB + 双臂/ee/gripper/lower_body/language；`ee` 动作是 base 系绝对目标位姿；数据相机为 rectified 头戴双目 + 双腕彩色；`meta/info.json` 自带双目 K/畸变/R/T 与腕部彩色 K；数据集还记录 `state_d435`、`state_torso`、base/torso 两套 ee pose；官方 Dex1 训练只用 3 路图（丢右目）；官方训练动作是相对表示，部署动作是绝对表示；DiverseManip 用 `cam_left_high/right_high` 且自述 binocular head。

### I10 自标定多视图几何融合（新） ★★★★★

**动机**
- 泛化轴里的位置/背景/干扰物/未见物体，本质都要求模型理解「物体在机器人坐标系里的 3D 位置与形状」；纯 2D token 要把这件事隐式学出来，样本效率低、外参一变就崩。
- 基线丢掉右目（F25），而评测端提供右目（F20）；数据集自带双目内参/外参（F23）；腕部手眼变换缺失但可自标定（H2）。这是「低成本、高杠杆」的观测侧空白。

**与现有方案差异**
- 基线：2D 图像 token → VLM → DiT，几何隐式。
- 常见改进：加深度图/点云，但直接用数据集外参硬编码，跨机器人易崩。
- 本点：**自标定 + 几何作为可微先验**——离线用示教数据估计 `T_ee_cam` 与 `T_base_head`；训练时用 3D 位置编码/辅助几何损失；推理时按标定置信度决定「硬几何」还是「软先验」。既吃几何红利，又留标定误差的退路。

**方法（三层，按风险从低到高）**
1. **L1 几何位置编码（默认，低风险）**：对每个图像 patch，用标定把像素反投影到 base 系 3D（头部双目用 stereo depth；腕部用单目深度或与头部融合的稀疏深度），把 3D 坐标经 Fourier/MLP 编码后加到 patch token 上。VLM 主干不变，只多一个位置编码分支。
2. **L2 辅助几何监督（中风险）**：加一个轻量 3D head，从 VLM 特征预测「目标物体 3D 中心/抓取点/夹爪目标 3D 位置」，用标定后的点云/深度 + 真值 action ee pose 监督。推理时该 head 可丢弃（零额外延迟），也可保留作几何一致性检查。
3. **L3 显式点云融合（高风险，缓）**：头部双目 + 双腕反投影 → base 系点云 → 轻量 PointNet/Transformer → 与 VLM token 交叉注意力。收益可能最大，但延迟/标定误差也最大；先用 L0 证明前两层不够再上。

**技术可行性**
- 中-高。标定：数据有 K/R/T（F23），腕部手眼用 PnP+SE(3) 平均即可起步；深度：双目 rectified（F22），可直接 SGBM/RAFT-Stereo；单目腕部深度可用现成模型，或用与头部的稀疏匹配做尺度对齐。
- 风险点是「标定迁移」，不是「算不出来」；因此把 L1/L2 做成可降级路径。

**所需资源**
- 标定：1×GPU 日/任务族（特征匹配 + PnP + 鲁棒平均）；可离线一次性完成。
- 训练：L1/L2 在官方 frozen-VLM/LoRA 单卡（F11）上可跑；L3 需 4–8 卡或更大 batch。
- 推理：L1 的 3D 位置编码几乎零成本；L2 的 3D head 可丢弃；L3 需额外 5–10ms。

**落地步骤**
1. 验证 H1–H3：在 3 个任务上核对相机键映射、`state_d435` 坐标系、双目 rectified 是否成立。
2. 标定 `T_base_head`（由 `state_d435`/`state_torso`/waist 链）与 `T_ee_cam`（头部双目作世界参考 + 腕部 PnP + SE(3) 鲁棒平均）。
3. 在留出集上报告标定残差：重投影误差（px）、跨任务 `T_ee_cam` 方差（cm/deg）。
4. 实现 L1 的 3D 位置编码，L0 对比「无几何 / 仅头部 / 头+双腕」。
5. 若 L1 增益不足，再加 L2 辅助损失；L3 仅在 L0 明确显示前两层饱和时启动。
6. L2 真机：单任务通道，优先选位置/背景轴扰动大的任务。

**风险与止损**
- **标定迁移风险（最大）**：数据集外参 ≠ 评测机器人。止损：L0 残差阈值（重投影中位数 >10px 或跨任务平移方差 >2cm/旋转 >2° → 不硬注入）；推理时用置信门控，低置信退回 2D。
- 双目在评测端是否同型号/同校正未证实（H1）。止损：先按 H1 做，若证伪则改用单目深度 + 本体尺度，或只用腕部几何。
- 腕部相机可能被遮挡/标定退化。止损：仅在头部与腕部同时可见足够特征时更新/使用手眼；否则退回 2D。
- 几何分支延迟。止损：按阶段选相机 + 低分辨率；p99 超预算先砍 L3，再砍 L1 的腕部分支。

### I11 跟踪残差接触代理（新） ★★★★

**动机**
- 赛题无任何力/触觉通道（前序 F8 复核）；接触任务族（PlugCharger、ZipUp、PourOutMedicine、Unlock 等）却最吃接触反馈。
- 但观测里有「命令」与「实际」两套 ee 位姿：`action.*_ee_pose_gripper_base` 是目标，`observation.state.*_ee_pose_gripper_base` 是实际（F24）。二者的差就是低层控制器在接触时「顶不上去」的残差——一个免费的力/接触代理。

**与现有方案差异**
- 纯视觉：接触瞬间的视觉变化小/被遮挡，检测滞后。
- 纯脚本阈值：不知道接触方向。
- 本点：用 `r_t = Log(T(a_t)^{-1}T(s_t))` 的**幅值+方向+持续时间**，融合腕部视觉接触证据，得到 `p(contact)`；作为策略输入/门控信号，而不是外挂控制器（避免 PR2 风险）。

**技术可行性**
- 高。`r_t` 直接由现有字段计算，零额外传感器；离线可在示教数据上验证。
- 需要标定「命令-实际」的时间对齐：若 `action` 是下一时刻目标，用 `a_t` 对 `s_{t+1}`；离线扫 lag `Δ` 取 AUC 最大者。若 action 只是 state 的重放（`a_t≈s_{t+1}`），则残差主要反映运动而非接触，本点应降级为「安全监控」而非接触检测。

**所需资源**
- 1 人周（离线统计 + 小型分类器/阈值 + 接入 I3/I5）。
- 无额外 GPU 训练成本；推理 <1ms。

**落地步骤**
1. 在 3–5 个接触任务上计算 `r_t`（同时试 `a_t` vs `s_t` 与 `a_t` vs `s_{t+1}`），用任务阶段/夹爪闭合/物体位移做弱标签，报告接触 vs 自由的 AUC。
2. 若 AUC >0.7：拟合阈值/逻辑回归/1D-CNN；否则只保留「幅值异常」作安全监控，不接入主链。
3. 与腕部视觉接触证据融合（简单加权/学习融合）。
4. 接入 I3 的伺服触发与 I5 的恢复触发；L2 单任务 A/B。
5. 与 I4 联合：区分「环境接触」（残差方向稳定、随动作增大）与「人手干预」（残差被持续外推、方向随人手变化）。

**风险与止损**
- 残差可能主要反映控制器滞后/动作幅值，而非接触。止损：AUC 不达标即砍；用「动作幅值归一化后的残差」和「方向一致性」做特征。
- 评测端低层控制器增益可能与示教不同。止损：只用相对变化/自适应阈值，不硬编码绝对力值。
- 单模型边界：只作为策略输入/门控，不触发脚本化恢复；若要用脚本恢复，归入 I5 的合规审查。

### 3.1 手眼自标定（离线，一次）

```python
def calibrate_hand_eye(task_data, K_head, R_stereo, T_stereo, K_wrist):
    Xs = []
    for frame in task_data:                      # 仅取头部与腕部同时可见足够特征的帧
        Z_head = stereo_depth(frame.head_left, frame.head_right, K_head, R_stereo, T_stereo)
        pts3d_head = unproject(Z_head, K_head)   # head camera frame
        T_B_H = pose_to_se3(frame.state_d435)    # H3: 先验证是 base 还是 torso 系
        pts3d_B = transform(pts3d_head, T_B_H)

        uv_wrist, idx = match_features(frame.wrist_left, frame.head_left)
        if len(uv_wrist) < N_MIN: continue
        ok, T_B_C = solve_pnp(pts3d_B[idx], uv_wrist, K_wrist)
        if not ok or reproj_error(T_B_C) > REPROJ_TAU: continue

        T_B_E = pose_to_se3(frame.ee_pose_base)
        Xs.append(inv(T_B_E) @ T_B_C)            # X = T_E_C

    X = robust_se3_average(Xs)                    # 平移中位数 + 旋转测地平均 + 离群剔除
    return X, residual_stats(Xs)
```

### 3.2 base 系 3D 位置编码（L1，默认）

```python
def geometry_positional_encoding(obs, calib):
    tokens_3d = {}
    # 头部双目：metric depth -> base 系
    Z = stereo_depth(obs.head_left, obs.head_right, calib.K_head, calib.stereo)
    P_B = unproject_to_base(Z, calib.K_head, calib.T_B_head(obs))   # [H,W,3]
    tokens_3d["head"] = fourier_mlp(P_B)

    # 腕部：单目深度或与头部融合的稀疏深度；用当前 ee pose + 手眼变换
    for side in ("left", "right"):
        Z_w = monocular_depth(obs[f"wrist_{side}"])                 # 或稀疏融合
        T_B_C = calib.T_B_E(obs, side) @ calib.X_ee_cam[side]       # 关键：手眼标定
        P_B_w = unproject_to_base(Z_w, calib.K_wrist[side], T_B_C)
        tokens_3d[side] = fourier_mlp(P_B_w)
    return tokens_3d        # 加到对应相机的 patch token 上；VLM 主干不变
```

```python
def contact_proxy(a_t, s_t, obs_wrist, history, lag=0):
    # 若 action 是下一时刻目标，用 s_{t+1}（lag=1）；lag 离线标定
    s = s_t if lag == 0 else s_{t + lag}
    r = se3_log(inv(pose_to_se3(a_t)) @ pose_to_se3(s))
    mag = norm(r[:3]); direction = normalize(r[:3])
    v = wrist_contact_evidence(obs_wrist)             # 物体位移/形变/遮挡
    p = contact_classifier(mag, direction, v, history) # 阈值/逻辑回归/1D-CNN
    history.append((mag, direction, p))
    return p
```

## 4. 实验设计（分级消融协议 v3）

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0-A | 标定：重投影误差、跨任务 `T_ee_cam` 方差、`state_d435` 链自洽 | 离线（免费） | 重投影中位数 ≤10px；跨任务平移 ≤2cm、旋转 ≤2°；链误差 ≤1cm/1° |
| L0-B | 几何表示：无几何 / 仅头部 / 头+双腕 / L1 vs L2 vs L3；位置/背景/干扰物/未见物体四轴 | 离线（免费） | 至少两轴 Δprog >0 且标称不降；延迟增量 ≤8ms |
| L0-C | 接触代理：3–5 接触任务的接触 vs 自由 AUC；lag 扫描 | 离线（免费） | AUC ≥0.7 才接入主链 |
| L1 | 2^(k-p) 析因：几何{on/off} × 相机{头/头+腕} × 标定{硬/软} | 离线 + 少量真机 | 主效应显著的 ≤3 组进 L2 |
| L2 | 真机：≥2 任务 × 各 2 次；优先位置/背景轴扰动大的任务 | 单任务通道 | 真机增益 ≥ 离线预测的 50%；标称不回退 |
| 门禁 | PR4：run_client 全流程 + p99 + 动作健康度 | 本地 stub | 0 拒绝动作、p99 < 40ms |

**Kill criteria**
- I10：H1 证伪且单目深度增益 <2 分 → 只保留 I10-L2 辅助损失或砍；标定残差超阈 → 不硬注入。
- I11：AUC <0.7 → 不接入 I3/I5，仅作安全监控。

## 8. 本轮最值得押注（一句话）

**押「观测侧几何」：先用官方已给的 `camera_params` + 自标定 `T_ee_cam`，把头部双目（含被基线丢掉的右目）与双腕 lift 到 base 系 3D，再以「3D 位置编码 + 辅助几何损失」的低风险形态注入——它不换模型、不碰单模型边界，却直接对准位置/背景/干扰物/未见物体四条泛化轴，且先手成本远低于再训一个数据引擎。**

## 9. 本轮最大风险（一句话）

**整套方案的命门是「数据集标定 + 自标定手眼变换能迁移到评测机器人」——若评测端相机/安装存在未建模偏差，显式几何会把像素噪声放大成系统性 3D 偏差；因此必须先用 L0 标定残差与跨任务一致性证伪，再决定硬注入还是仅辅助监督。**
