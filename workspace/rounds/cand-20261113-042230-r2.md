# 第 3 轮迭代（灵感循环 v3：「语音交互」×「双臂协作」）—— 从「扰动恢复」到「人因接口 × 双臂角色」

> 承接状态文件中的 v2 清单（UIP-01′~15）。v2 的旗舰是「扰动撤回检测-重做」，由 Gazebo 判分（UIP-11）与扰动-恢复数据工厂（UIP-12）支撑。本轮两个灵感词看似是“加语音、加手臂”，但核对接口后得到两个反直觉结论：**语音在运行时不在接口里，双臂则本来就在接口里**。所以本轮不是简单叠加，而是把“人的接口”与“机器的协作”各自放到正确的位置：语音只做离线的“人→符号”监督与授权；双臂必须做**角色非对称**的协同，而不是两个独立单臂。

> 这两条结论把本轮从“堆模块”拉回到“可证伪的研究问题”：语音的离线标签是否真的能提升 `regressed` 检测？双臂角色是否真的比“单臂 + 空闲手”更能救步骤分？两者都必须用消融实验回答。

## 1. 直觉解释：两个词各自真正的杠杆

### 1.1 语音：它是“人的接口”，不是“机器人的传感器”

最直觉的做法是“加一个麦克风，做语音指令”。但赛制里没有 audio 通道，评测是自主的，数据视频也没有音轨。运行时依赖语音会同时踩两条红线：**接口外输入**与**非单模型/外部服务**。

更合适的直觉是：语音是**人类把意图、顺序、纠错压缩成低带宽符号**的方式，而“子目标顺序”和“纠错”正是 v2 最缺的东西。人类在教机器人时不会说 14 维关节角，而会说“先扶住”“再拧”“它又开了，重来”“换只手”。这些短语恰好对应我们需要的 `anchor / guard / handoff / regressed` 语义。因此语音的正确位置是**离线监督**：把人的话变成帧级标签，再蒸馏进只看视觉/状态的验证器与角色选择器。

一句话：**语音不是策略的输入，而是策略的“老师”**。

### 1.2 双臂：不是“两个单臂”，而是“角色 + 约束 + 交接”

如果把左右臂当成两个独立策略，会得到三个问题：动作不同步、对象坐标系不一致、容易自碰撞；更糟的是，验证器会把“左手把物体交给右手”误判成“左手把物体弄丢了”，从而触发错误的 `regressed` 重做。

更合适的直觉是：人类双手协作的核心不是“两只手都在动”，而是**角色非对称**——一只手锚定/稳定，另一只手操作；或者一只手守卫已完成的进度，另一只手去恢复；需要时再**交接**。这把 14 维双臂控制压缩成“角色 + 少量协调约束”，既降搜索空间，又直接服务于步骤分。

一句话：**双臂的杠杆在“角色”，不在“自由度”**。

## 2. 严谨定义

### 2.1 可采纳的语音通道：离线、可蒸馏、非运行时

**定义 1（离线语音通道）**：设策略为 `π_θ(a|o)`，`o` 只包含接口目录中的键。语音通道是一个离线映射 `V: speech → Y`，其中 `Y` 是标签集合（如 `regressed / retry / handoff / guard / advance`）。它只用于构造增强数据集 `D' = D ∪ {(o_t, V(s_t), a_t)}`，或用于授权技能图/判据；提交时不存在任何从 audio 到 `a` 的边。形式化地，`π_θ(a|o)` 的输入域不含 audio，且推理期不调用外部 ASR/TTS/LLM。

**定义 2（VSRD，Voice-Supervised Recovery Distillation）**：给定带时间戳的语音 `(s, τ)`、观测 `o_{1:T}`、动作 `a_{1:T}`，对齐器 `A` 产生事件区间 `E = {(y_k, [t_k^0,t_k^1])}`；标签器 `L` 把事件映射到恢复意图 `y ∈ Y`。训练一个只看 `o_t` 的验证器/角色选择器 `f_φ(o_t, g)`，最小化

```text
L_VSRD(φ) = Σ_t CE(f_φ(o_t, g_t), y_t) + λ·L_aux(a_t, o_t)
```

其中 `L_aux` 是动作/接触辅助损失。推理期 `f_φ` 不含语音输入；语音只存在于训练管线。

**合规条件（必须同时满足）**：

1. `metadata.obs_delta_indices` 不声明任何 audio 键（接口也没有）；
2. `get_action` 不读取麦克风、不调用外部服务；
3. 所有语音工具（ASR/TTS/本地 LLM）只在离线数据/授权阶段使用；
4. 最终提交是**一条共享骨干**的策略；验证器若是学习式的，必须是主骨干的蒸馏头，而不是独立大模型。

**定义 3（语音授权的技能图）**：研究者用语音描述任务分解，离线编译为 `G=(V,E)`，节点是技能/子目标，边是顺序与恢复分支；每个节点附带**可观测的几何谓词** `p_v(o)`。语音只改变 `G` 的构造速度与覆盖面，不改变运行时接口。

### 2.2 双臂角色 MDP：把“协作”写成可执行的对象

**定义 4（角色增强的双臂策略）**：角色状态 `ρ_t = (ρ_t^L, ρ_t^R)`，`ρ ∈ {ACT, ANC, GRD, IDLE}`，分别表示主动操作、锚定/稳定、守卫/遮挡管理、空闲。双臂策略为

```text
π_θ(a_L, a_R | o_t, g, ρ_t)
```

由共享视觉-语言骨干 `z_t = Enc(o_t)`、角色嵌入 `e(ρ_t)` 与两个动作头组成；协调层 `Π_C` 把原始动作投影到满足约束的集合：

```text
C = {无自碰撞, 对象坐标系一致, 接触/时序 precedence, 力/位姿安全}
```

角色转移是一个有限状态机 `ρ_{t+1} = F(ρ_t, V(o_t,g), D(o_t), budget)`，其中 `V` 是进度验证器，`D` 是扰动检测器。

**定义 5（交接谓词）**：交接事件 `H` 表示物体从手 A 转移到手 B。其成功谓词为

```text
H_success(o) = [grasp_B(o)] ∧ [release_A(o)] ∧ [pose_error(obj) < ε]
               ∧ [Δt < Δ_max] ∧ [no_drop]
```

验证器必须同时输出**物体所有权** `owner(o) ∈ {L,R,both,none}`；否则“交接”会被误判为“撤回”。

**定义 6（双臂必要性与协调度）**：从公开数据估计

```text
β(task) = E_t[1(||a_L(t)||>ε ∧ ||a_R(t)||>ε)]
κ(task) = corr_t(||a_L(t)||, ||a_R(t)||)
η(task) = E_t[1(||a_L(t)||>ε)] / E_t[1(||a_R(t)||>ε)]
```

`β` 高表示天然双手；`κ` 高表示同步协作；`η` 偏离 1 表示单手主导。它们不是“感觉”，而是可以从 32 个 HF 数据集直接算出的**任务排序**，用于决定 BAR 的训练/评测重点。

### 2.3 这些定义如何改写 v2 清单

- **UIP-01′ → UIP-01″**：验证器从 `done/ongoing/fail/regressed` 扩展为 `done/ongoing/fail/regressed/handoff`，并输出 `owner`；避免把交接误判为撤回。
- **UIP-09′ → UIP-09″**：恢复动作从“同手重做”扩展为 `redo / guard / handoff / present` 四选一，由角色状态与置信度决定。
- **UIP-14 → UIP-14′**：技能图节点从“单臂技能”变成“双臂角色模板”，边包含交接。
- **UIP-11/12/13/15**：GSO 判分加 `held_by/stable/handoff` 谓词；DRF 生成“针对主动手”的扰动与语音标签；ACS 在“双手同时接触”的协调关键阶段用小 `k`；CSG 给交接/自碰撞/重做设预算。
- **新增 UIP-16 VSC**：离线语音监督编译器；**UIP-17 BAR**：双臂非对称角色策略；**UIP-18 XH**：跨臂交接/守卫执行器。

## 3. 证据驱动的假设

- **H5（角色 > 自由度）**：在接触密集/需要稳定的任务上，`ANC/GRD` 角色带来的步骤分增益，大于把双臂当两个独立单臂的增益；消融“辅助臂空闲”应显著掉分。
- **H6（交接是双刃剑）**：跨臂交接能救“主动手被干扰/被遮挡”的 episode，但会引入掉落与自碰撞；只在 `regressed` 高置信且物体稳定时触发，收益才为正。
- **H7（语音只值“标签”）**：VSRD 对 `regressed` 检测的增益，主要来自**帧级监督标签**，而不是语音本身；若用人工视觉标注替代语音，增益应接近。这个假设能直接检验“语音是否只是昂贵的标注工具”。
- **H8（语言鲁棒性是次要战场）**：TTS/ASR 复述对“未见物品”语义有帮助，但若评测语言固定，收益有限；优先级低于 VSRD 与 BAR。

**测量计划（先测量，再下注）**：

1. 在 32 个公开数据集上算 `β/κ/η`，得到“天然双手任务榜”；
2. 在 3–5 个高 `β` 任务（如 T16 叠毛巾、T19 拉链、T14 倒药、T31 文具袋）上做“辅助臂空闲 vs 锚定 vs 守卫”的离线回放；
3. 用 GSO（UIP-11）做角色感知的步骤分代理，先验证“角色”是否改变步骤分，再谈真机。

## 4. 候选草案与合并

本轮围绕两个词发散 9 个草案：

| 草案 | 来源词 | 判断 | 合并去向 |

## 5. 本轮最大风险

**一句话**：最大风险不是“语音识别不准”或“双臂太难”，而是**把语音当运行时输入、把双臂当两个独立单臂**，从而同时踩合规与协调的红线；更隐蔽的是，离线语音标签与仿真双臂数据会制造出“看起来会协作”的假进展，而真机上的手眼标定、自碰撞与交接失败根本没有被测量。

## 1. 旗舰深潜：UIP-01″ · RHPV-D+R（Role-aware Rolling-Horizon Progress-Verified with Disturbance-awareness）

### 1.1 机制

动作块 `A=(a_1..a_{T_a})` 不整段盲执行。每 `k` 步用**角色感知验证器** `V(o_t, g, ρ_t)` 判断当前子目标 `g` 的状态：

```text
state ∈ {ongoing, done, regressed, handoff, fail}
owner ∈ {L, R, both, none}
```

其中 `regressed` 表示“子目标从 done 回退到 undone”（人为撤回/滑落），`handoff` 表示“物体从一手转到另一手但进度未丢”。验证器必须同时输出 `owner`，否则“交接”会被误判为“撤回”。

### 1.2 状态机

```text
ongoing ──done(任一臂, owner一致)──> done[g+1]
done ──进度回退──> regressed ──(guard/handoff/redo)──> ongoing
done ──物体换手──> handoff ──(交接成功)──> done[g, owner更新]
fail ──低置信/超时──> retry 或回退到上一子目标
```

### 1.3 恢复原语选择

```text
if state == regressed:
    if free_hand and object_stable and conf > τ_guard:
        choose GUARD          # 辅助手稳住/护住，主动手重做
    elif can_handoff and handoff_budget > 0 and conf > τ_handoff:
        choose HANDOFF        # 辅助手接管，主动手释放
    elif occluded(active_hand):
        choose PRESENT        # 辅助手把对象移入视野
    else:
        choose REDO           # 同手重做
```

```python
        self.role_prior = role_prior      # 由 UIP-16 蒸馏，只看 obs
        self.skill_graph = skill_graph
        self.K_MAX = K_MAX
        self.conf_thr = conf_thr
        self.max_redo = max_redo
        self.max_handoff = max_handoff
        self.latency_budget_ms = latency_budget_ms

    def reset(self):
        self.policy.reset()
        self.g = 0
        self.redo = 0
        self.handoff = 0
        self.roles = ("IDLE", "IDLE")
        self.owner = "none"
        self.buf = []

    def get_action(self, obs):
        if not self.buf or self._need_reobserve(obs):
            self.roles = self.role_prior(obs, self.g, self.roles)
            state, conf, owner = self.verifier(obs, self.g, self.roles)
            if conf >= self.conf_thr:
                if state == "done" and owner == self.owner:
                    self.g += 1
                    self.redo = 0
                    self.handoff = 0
                elif state == "handoff":
                    self.owner = owner
                elif state == "regressed":
                    self._recover(obs, conf)
                elif state == "fail" and self.redo < self.max_redo:
                    self.redo += 1
            k = self._pick_k(obs, self.roles)   # ACS: 协调关键阶段用小 k
            self.buf = list(self.policy.get_action(obs, self.roles, k))[:k]
        return self.buf.pop(0)

    def _recover(self, obs, conf):
        free = self._free_hand(self.roles)
        if free and self._object_stable(obs) and conf > 0.7:
            self.roles = self._set_role(free, "GRD")
        elif self._can_handoff(obs) and self.handoff < self.max_handoff and conf > 0.8:
            self.handoff += 1
            self.roles = self._swap_roles(self.roles)
        elif self._occluded(obs) and free:
            self.roles = self._set_role(free, "GRD")
        elif self.redo < self.max_redo:
            self.redo += 1

    def _need_reobserve(self, obs):
        return True     # 每个 k 步块结束后重观测；实现中按 buf 长度触发
```

### 1.5 与 v2 差异

- v2 只有 `done/fail/ongoing/regressed`；v3 增加 `handoff` 与 `owner`，直接来自“双臂动作契约”这一接口事实。
- v2 的恢复默认“同手重做”；v3 把恢复变成**角色动作**，由 UIP-17/18 提供可执行原语。
- v2 的验证器是单臂视角；v3 的验证器必须回答“哪只手拥有物体”，否则会把正常的左右手交接误判成撤回。

### 1.6 风险

误判 `owner` 会导致“反复重做/反复交接”。必须用 UIP-15 的三重护栏：置信度门限、最大重做/交接次数、延迟预算；并在 GSO 中先做角色感知回放，再上真机。

## 2. UIP-16 · VSC（Voice-Supervised Compiler，语音监督编译器）

### 2.1 直觉

语音不是运行时传感器，而是**人类教师的低带宽符号通道**。它最适合传递两类信息：**子目标顺序**与**纠错意图**。这两类信息恰好是 v2 的验证器与恢复策略最缺的监督。

### 2.2 离线管线

1. **采集**：真机/仿真遥操作 + 脚本化干扰 + push-to-talk。用事件标记（按键/闪光/时间码）把语音与机器人帧对齐。
2. **ASR**：本地 Whisper/CTC，输出词级时间戳；只在离线使用，不进入提交。
3. **对齐**：事件标记 + 动作阶段分割 + DTW；得到 `(y, [t0,t1])`。
4. **标签集**：`regressed`、`retry`、`handoff`、`guard`、`present`、`advance`。
5. **蒸馏**：训练 `V_φ(o_t,g)` 与角色先验 `R_ψ(o_t,g)`；输入只含 `o_t`（图像/状态/文本语言），**不含 audio**。
6. **授权**：语音描述 → 技能图/几何谓词；人工审核后写入 GSO（UIP-11）与 MSGR-B（UIP-14′）。

### 2.3 数据 schema

| 字段 | 含义 |
|---|---|
| `episode_id` | 同一段遥操作/干扰 |
| `t` | 机器人帧号（30 fps） |
| `speech_text` | ASR 文本（仅离线） |
| `speech_span` | `[t0,t1]` 对齐区间 |
| `intent_label` | `regressed/retry/handoff/guard/present/advance` |
| `role_label` | `(L,R)` 角色弱标签 |
| `obs_keys` | 接口可用的观测键子集 |
| `action` | 左右臂/夹爪/pivot 目标 |

### 2.4 伪代码

```python
# ===== offline only: never imported by the submitted policy =====
def build_voice_supervised_data(episodes, asr, aligner, labeler):
    D = []
    for ep in episodes:
        words, ts = asr(ep.audio)                 # local ASR, offline
        events = aligner(words, ts, ep.markers, ep.frames)
        for text, (t0, t1) in events:
            y = labeler(text)                      # intent + role
            for t in range(t0, t1 + 1):
                D.append((ep.obs[t], ep.goal[t], y, ep.action[t]))
    return D

def train_distilled_verifier(D, backbone):
    verifier = DistilledHead(backbone)            # same backbone, one model
    for obs, goal, y, action in D:
        logits = verifier(obs, goal)              # no audio input
        loss = CE(logits, y) + lambda_aux * aux(action, obs)
        loss.backward()
    return verifier
```

### 2.5 合规

- 语音只在离线数据管线；提交的 `get_action` 不读麦克风、不调用 ASR/TTS/LLM。
- 验证器是主骨干的蒸馏头，不是独立大模型；满足“单模型”口径。
- 若外部 ASR 工具本身有合规疑虑，可改用 organisers 提供的文本语言或人工转写；语音只是**采集界面**，不是提交依赖。

### 2.6 消融

- 语音标签 vs 人工视觉标签 vs 无标签：检验 H7（语音是否只值“标签”）。
- 跨任务留出：在未见干扰类型/未见任务上测 `regressed` F1 与恢复步骤分。
- ASR 噪声注入：词错率 5%/10%/20% 下的标签稳定性；用事件标记而非仅时间戳对齐来降噪。

### 2.7 风险

ASR/对齐错误会把“重做”标成“前进”，污染验证器；语音也可能只提供昂贵的人工标注替代品。必须用 held-out 任务与人工视觉标注做对照。

## 3. UIP-17 · BAR（Bimanual Asymmetric Roles，双臂非对称角色）

### 3.1 角色集

| 角色 | 含义 | 典型动作 |
|---|---|---|
| `ACT` | 主动操作手 | 抓、插、拧、拉、放 |
| `ANC` | 锚定/稳定手 | 按住物体、固定容器、抗旋转 |
| `GRD` | 守卫/遮挡管理 | 护住已完成结构、移开遮挡、把对象呈现给腕相机 |
| `IDLE` | 空闲/回退 | 单臂任务时保持安全收拢，避免乱动 |

### 3.2 角色先验

角色由三路信息决定：

```text
ρ_t = R_ψ( observation.language, first_frame_layout, action_history, V(o_t,g) )
```

- **语言**：`observation.language` 中的动词/介词提示单手或双手（“fold”“hold”“open and pour”）。
- **首帧布局**：物体是否分散、是否需要固定容器。
- **历史与验证器**：刚刚是否发生 `regressed`/`handoff`，当前哪只手拥有物体。

### 3.3 架构

```text
                 ┌── role embedding e(ρ_L) ──> left head  ──┐
obs ──> shared Enc ──> z_t ──┤                              ├──> Π_C ──> (a_L, a_R)
                 └── role embedding e(ρ_R) ──> right head ──┘
```

- **一条共享骨干**（视觉-语言-状态编码），左右动作头共享大部分参数，仅角色嵌入与输出头分离。
- `Π_C` 是协调投影层：无自碰撞、对象坐标系一致、接触/时序 precedence、力/位姿安全。
- 单臂任务时，辅助手默认 `IDLE`，并由正则项惩罚“无意义的大动作”，避免伤可信度。

### 3.4 训练目标

```text
L = L_imit + λ1·L_role + λ2·L_coord + λ3·L_recovery
```

- `L_imit`：公开数据双臂动作（joint 或 ee，二选一）。
- `L_role`：由 UIP-16 语音标签/规则生成的弱角色标签。
- `L_coord`：对象坐标系一致、无自碰撞、双手时序 precedence。
- `L_recovery`：UIP-12 的“干扰→撤回→恢复”三元组。

### 3.5 推理伪代码

```python
class BimanualRolePolicy:
    def __init__(self, trunk, left_head, right_head, coord, role_prior):
        self.trunk = trunk
        self.left_head = left_head
        self.right_head = right_head
        self.coord = coord
        self.role_prior = role_prior

    def act(self, obs, goal, roles):
        z = self.trunk(obs)
        roles = self.role_prior(obs, goal, roles)
        aL = self.left_head(z, role_embed(roles[0]), goal)
        aR = self.right_head(z, role_embed(roles[1]), goal)
        aL, aR = self.coord.project(aL, aR, obs, roles)
        return aL, aR, roles
```

### 3.6 为什么不是两个模型

- 左右臂共享骨干与大部分参数；角色嵌入是条件，不是第二个网络。
- 输出仍是一个 `get_action` 返回的左右双臂动作字典，满足接口契约。
- 训练/推理只加载一份权重；显存与延迟可控。

### 3.7 风险

角色标签噪声会让辅助手“帮倒忙”；协调层过强会压制必要的单手动作。用软角色（概率分布）+ 通用回退头 + `IDLE` 正则缓解。

## 4. UIP-18 · XH（Cross-arm Handoff / Guard，跨臂交接执行器）

### 4.1 四个原语

| 原语 | 触发 | 动作 | 安全条件 |
|---|---|---|---|
| `GUARD` | `regressed` 高置信，辅助手空闲 | 辅助手稳住/护住已完成结构，主动手重做 | 不与人对抗；力/位姿限幅 |
| `HANDOFF` | 主动手被遮挡/被干扰，物体稳定 | 辅助手接管，主动手释放，角色互换 | 交接次数上限；无掉落 |
| `PRESENT` | 主动腕相机被遮挡 | 辅助手把对象移入视野 | 不遮挡另一相机；轨迹无碰撞 |
| `REDO` | 无自由手/低置信 | 同手重做 | 重做次数上限 |

### 4.2 触发与安全阀

```python
def choose_primitive(obs, g, roles, state, conf, budget):
    if state != "regressed":
        return "none"
    free = free_hand(roles)
    if conf < 0.6:
        return "redo"
    if free and object_stable(obs) and conf > 0.7 and budget.guard > 0:
        return "guard"
    if can_handoff(obs, g) and conf > 0.8 and budget.handoff > 0:
        return "handoff"
    if occluded(active_hand(roles)) and free:
        return "present"
    if budget.redo > 0:
        return "redo"
    return "abort"
```

### 4.3 交接安全

- **自碰撞**：交接前检查两臂工作空间重叠；用 `Π_C` 的碰撞约束。
- **掉落**：只有物体稳定且双手夹爪都在可用状态时才交接；否则回退 `REDO`。
- **人的安全**：`GUARD` 不是“与人抢物体”，而是稳定接触/防止误碰；检测到人持续施力时让出，转 `REDO`。
- **可信度**：交接会产生动作统计突变；CSG 限制单位时间交接次数与动作抖动。

### 4.4 风险

交接是 v3 最“脆”的原语：手眼标定误差、腕部奇异、夹爪时序错位都会导致掉落。只在 GSO 与真机上都验证过的任务上启用，默认回退 `REDO`。

## 5. 先测量：双臂必要性与协调度

在 32 个公开数据集上计算：

```text
e_L(t) = ||a_L(t)||,  e_R(t) = ||a_R(t)||
β(task) = mean_t [1(e_L(t) > ε ∧ e_R(t) > ε)]
κ(task) = corr_t(e_L(t), e_R(t))
η(task) = mean_t [1(e_L(t) > ε)] / mean_t [1(e_R(t) > ε)]
```

- **高 β**：天然双手任务，优先做 BAR/XH 与角色感知 GSO。
- **低 β 但高扰动**：单臂任务，辅助手以 `GRD/ANC` 为主，不要强行双手操作。
- **η 明显偏离 1**：左右手主导差异大，角色先验应允许“惯用手”偏置。

**预期**（待数据验证）：T16 叠毛巾、T19 拉链、T14 倒药、T09 工具箱、T31 文具袋的 `β` 较高；T01 挂杯、T02 水果收集等以单手为主。该排序直接决定 UIP-17 的训练采样权重。

## 8. 合规与风险

- **语音红线**：接口无 audio，`observation.language` 只是文本；任何运行时 ASR/语音命令都不可提交。UIP-16 只在离线管线使用语音，提交物是蒸馏后的单模型。
- **单模型红线**：UIP-17 是共享骨干 + 角色条件头，不是左右两个模型；UIP-16 的验证器是主骨干蒸馏头，不是外部大模型。
- **双臂红线**：动作契约要求左右双臂键；不能只返回单臂。辅助手不能“为了刷动作”而乱动，CSG 要惩罚无意义动作。
- **人因安全**：`GUARD` 不是与人对抗；检测到人持续施力时让出，转 `REDO`。交接要避免夹手与碰撞。
- **仿真过拟合**：GSO 只做“结构/顺序/角色”裁判；视觉/接触成败仍需真机锚点（E208/E210）。
- **手册未取到**：5 轴中的位置/干扰物/背景，以及评测轮次/时限/控制频率，仍待飞书手册公开后核实。

## 10. 本轮最大风险 & 押注

**→ 押注**：**UIP-01″ + UIP-09″ + UIP-17 + UIP-18** 组成的“角色感知扰动恢复闭环”，由 **UIP-16** 的离线语音监督提供标签、**UIP-11** 的 GSO 提供结构判分、**UIP-13/15** 控制实时性与安全。它把 v2 的“检测撤回→重做”升级为“检测撤回→按角色选择守卫/交接/重做”，直接对准规则里白纸黑字、公开数据完全空白、且选手权限内可闭环的最大得分缺口。

**一句话最大风险**：如果语音只被当成“昂贵的标注工具”、双臂只被当成“两个独立单臂”，那么 v3 的增益会全部来自仿真与标注的自我循环，而真机上的手眼标定误差、自碰撞与交接掉落会把“步骤分提升”打回原形。
