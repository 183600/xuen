## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（多机器人协作 → 赛题本来就是多机器人，只是「协作」不在操作层，在服务层）**
直觉：字面读「多机器人协作」是范畴错误——32 个考题都是单台 G1 Dex1 的单/双臂操作，没有「两台机器人抬一个箱子」的计分项。但评测基础设施本来就是多机器人的：N 台测试机器人、N 个端口、随机顺序、可能同时被调用（F20/F21）。所以「协作」的正确落点不是让机器人互相配合，而是让 **N 个策略实例共享只读资源（冻结权重、预填充缓存、检索索引、标定表），同时严格隔离可变经验（每集状态、历史栈、随机数）**。反直觉点：**最好的多机器人协作，往往表现为「反协作」——把状态隔离、让故障快速失败，只共享不可变知识。** 舰队里真正的敌人不是「配合不好」，而是**尾部风险**：一个端口 OOM、一次推理卡死、一个端口数不对、一次状态串台，就会把一整台机器人的所有 episode 归零。

**灵感 2（交互设计 → 策略的用户是「带 SLO 的评测器」和「在场的人」）**
直觉：交互设计在这里不是 UI，而是**契约**。F23 说明契约在握手时冻结：T_a 不能中途变、控制空间不能切、历史栈长度不能改；F24 说明延迟抖动与动作离群不是「工程指标」，而是**会被记录、可能随榜单展示的可信度信号**；F25 说明即使只用一只手，闲置手臂与 pivot 也必须给出合法且「不添乱」的动作。因此交互设计的核心不是「让模型更强」，而是**让系统在非标称时刻仍然可预测、可让位、可降级**：观测陈旧时保持、有人手靠近时让位、模型超时时返回预置安全 chunk、动作永远良构且平滑。反直觉点：**在固定 T_a 的契约下，「自适应 chunk」在协议层是非法的；能自适应的只能是 chunk 内部的形状与状态机，而不是 chunk 长度。**

**碰撞与统一**：把两个灵感合起来，得到**舰队交互协议（Fleet Interaction Protocol）**：N 个隔离端口，每个跑一个本地交互状态机（NOMINAL / INTERFERED / STALE / DEGRADED / FAULT），共享一个只读知识后端与一个有界并发的推理后端，由一个舰队监督器统一做准入控制、看门狗与遥测；遥测只用于赛后离线分析，绝不在评测期更新权重。它和第 2 轮的数据引擎是**乘法关系**：数据引擎抬高期望分，舰队交互协议防止期望分被「零可用率」乘掉、并压低方差。第 2 轮结论因此修正为：**中期胜负手 = 数据引擎（期望）× 交互契约（方差与尾部）；先过可靠性门槛，再把剩余预算押数据。**

## 2. 对第 2 轮痛点的增量修订

- P1（弱任务支配平均分）升级为 **P9（舰队尾部风险）**：单实例层面的弱任务只是拉低平均；舰队层面一个端口失效会把整台机器人的分数清零，尾部比均值更致命（全舰队健康概率 A ≈ p^N）。
- P2（泛化缺口）不变：仍由 I1/I2/I9 主攻。
- P3（人手在场）升级：从「检测到人手就停」升级为「预测接近→提前让位→稳定后恢复」的交互状态机（I11）。
- P4（无触觉）不变：I3 与孪生语料仍是主缓解。
- P5（时间压力）补充：单步预算 ≈66ms（F12），但评测器单步超时/重试语义**未知**；交互层必须自带预算与兜底，而不是假设评测器会等。
- P6（部署）升级为 **P10（交互可信度）**：参考服务串行、无批处理、无超时（F22）；延迟抖动/动作离群会被记录并可能公开（F24）。
- P7（先手窗口）不变。
- P8（示教质量）不变。
- 新增 **P11（契约刚性）**：T_a/控制空间/历史栈在握手时冻结（F23），任何依赖运行期改变这些的旧设计（尤其第 2 轮 I4 的「自适应 chunk」）必须重写。

## 3. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

- **Q9（舰队调度与故障隔离）**：在 N 未知、模型单卡可跑（F11）、单步 ≈66ms 的约束下，共享后端应采用何种「小窗口动态批处理 + 有界队列 + 每请求 deadline + 每端口会话隔离」策略，才能同时约束每端口 p99 与总吞吐？一个端口卡死时，如何保证其余端口 p99 不被传染？安全 N/GPU 是多少？
- **Q10（交互契约的最小安全状态机）**：在 T_a 固定、无触觉、无心跳、评测器超时语义未知的条件下，怎样的状态机 + anytime 安全兜底能保证「任何时刻都返回合法、准时、不添乱的动作」？闲置手臂/pivot 的 do-no-harm 动作如何定义与验证？
- **Q11（只读协作的完整性边界）**：哪些跨端口共享是诚信安全的（冻结权重、按指令键的预填充缓存、离线检索索引、标定表），哪些绝对禁止（可变 episode 状态、评测期在线更新、跨端口梯度）？如何用测试证明「共享只读、隔离可变」而非仅仅声明？

## 4. 设计原则（新增 PR6–PR8，PR1–PR5 保留）

- **PR6 可用率乘数律**：任何可能把某个 episode 归零的组件（端口、序列化、超时、状态串台）都必须先过可靠性门槛，才允许接入计分通道；可靠性不是功能，是乘数。
- **PR7 契约先行**：所有运行期行为必须从握手冻结的 metadata 推导；把 `example_env.py` 的校验器纳入本地 CI，任何「协议层小聪明」默认视为违规。
- **PR8 只读协作、状态隔离**：跨实例只共享评测前冻结的只读产物；可变经验（episode 状态、历史、随机数、缓存写入）严格 per-port；评测期满足 `∂θ/∂eval = 0`。
- PR1–PR5 保留（第 1/2 轮 §4）。

## 6. 本轮最大风险

**一句话**：把「多机器人协作」做成共享后端后，**耦合会放大尾部延迟**——一个端口的慢请求或一次坏批处理会通过动态批处理把 p99 传染给全舰队，反而制造了它本想消除的失分尾部；若 N 很小（如 N≤2）且独立进程装得下模型，整套 I10 就是抢走数据引擎预算的过度工程。因此 I10 必须以「N 与超时语义核实 + N 客户端 soak + 故障注入」为放量前提，并保留「退回进程隔离」的裁撤线。

## 7. 下轮迭代计划（深化与修剪，不推倒）

- **深化**：I11（状态机与兜底动作的形式化 + 用本地 example_env 建契约 CI）；I10（动态批处理/准入控制的排队论估算 + N 客户端故障注入 soak）；I9（预填充缓存按 instruction 键的命中率与内存上界）。
- **修剪**：I4 的「自适应 chunk」正式废弃（F23）；I7 增加「挤占 p99 即裁」判据；若 N≤2 且模型可多进程常驻，I10 降级为「进程隔离 + 监督器」，不做动态批处理。
- **待核实**：N 的真实值；评测器单步超时/重试/断线重连语义；交互质量是否参与计分还是仅展示；端口数不匹配/单端口挂掉的判定方式；共享后端是否被允许（README 明示允许，仍需书面确认）。

- 本轮补：接触段的低置信回退动作必须纳入 I11 的安全动作集，避免「伺服失败」与「模型超时」两套兜底互相打架。

### I4 v3 固定 chunk 下的人机交互门控 ★★★★（重写）
- **动机**：第 2 轮 I4 假设「干预态短 chunk / 稳定态长 chunk」；F23 证明 `action_chunk_size` 在握手时冻结、每个动作数组必须恰为 `(T_a, …)`，**运行期自适应 chunk 在协议层非法**。
- **本轮重写**：把「自适应」从协议层移到 chunk 内容与状态机：
  1. **T_a 设计期选型**：小 T_a → 重规划频繁、暴露网络延迟；大 T_a → 盲执行长、干预响应慢。用 L0 离线回放 + 实测网络延迟分布选候选（8 / 16），不追求运行期可变。
  2. **让位尾段（yield tail）**：检测到人手接近时，即使当前 chunk 未执行完，也把**剩余步骤改写**为预计算的安全让位序列（减速→退避→保持）；因为不能返回更短 chunk，只能在固定 T_a 内改写尾部动作。
  3. **接近预测 + 滞回恢复**：手部检测框中心/尺度/速度 → 估计进入工作空间的剩余时间；提前进入 INTERFERED；手离开且场景稳定 k 帧后进入 RECOVERING，恢复首 chunk 降速。
  4. **闲置臂 do-no-harm**：非任务臂收拢到预标定 tuck pose，pivot 保持，夹爪保持；所有动作过限幅/有限性/平滑 guard（F25）。
- **与现有方案差异**：不再声称运行期改 chunk；把「自适应」限定为 chunk 内动作形状与状态机转移，契约合规（PR7）。
- **技术可行性**：高。纯规则 + 视觉检测 + 预计算轨迹，不需新模型。
- **所需资源**：1 人周工程 + 真机 1 天标定 tuck pose / 让位速度。
- **落地步骤**：①T_a 候选的 L0 回放；②让位尾段与安全动作集；③手接近预测与滞回；④闲置臂 tuck 标定；⑤真机人为干预 A/B（有/无让位尾段）。
- **风险**：固定 T_a 使干预响应受限于 chunk 粒度；让位尾段可能与任务进度冲突；无触觉下接近预测有误报/漏报。

### I5 v2 非标称示教合成 + 得分点对齐恢复 ★★★★（维持）

### I6 v2 每端口确定性服务 ★★★★（升级）
- **动机**：参考 `PolicyService` 单连接串行、同步调用、无超时（F22）；评测器每步记录延迟与波动（F24）；契约在握手冻结（F23）。
- **本轮深化**：I6 只管**单端口内部**的确定性，跨端口调度交给 I10：
  1. **同步模型调用移出事件循环**：用有界 worker（线程/子进程）执行 `get_action`，事件循环只做收发，避免一个端口阻塞其他协程。
  2. **每请求 deadline**：超过预算即触发 I11 的 anytime 兜底，而不是无限等待。
  3. **本地契约校验**：复用 `example_env.py` 的 shape/dtype/token/键集合检查，再加有限性、关节限幅、抖动上限；CI 与运行时双保险。
  4. **动作整形**：chunk 内最小加加速度插值、速度/加速度限幅、闲置臂 tuck；保证良构与平滑。
  5. **可观测**：`/healthz`、每步延迟、动作统计、状态迁移结构化日志。

- **所需资源**：1 人周；无额外 GPU。
- **风险**：线程/子进程与 CUDA 上下文的兼容性；deadline 只能「放弃等待」不能安全中断同步调用（需进程隔离或分段推理）。

### I10 舰队级监督与故障隔离（新） ★★★★★
- **动机**：N 台机器人、N 端口、随机顺序、可能并发（F20/F21）；参考实现不并发（F22）；一个端口失效清零一台机器人（P9）。
- **设计**：
  1. **N 无关启动**：从 `UNIBOT_N`/配置读取 N，严格暴露 `8765..8765+N−1`；启动自检端口数与 `/healthz`；缺失/多余端口即失败（F20）。
  2. **两种后端模式**：A「进程隔离」（N 份模型，适合小模型/小 N）；B「共享后端」（1 份权重 + N 轻端点 + 有界 worker 池）。默认 B；若内存允许且 N≤2，退回 A。
  3. **有界并发 + 准入控制**：每端口最多 1 个 in-flight；全局队列有界；小窗口动态批处理（如 5–10ms 窗口、batch≤B）；队列超阈值时对非接触段/低优先级端口返回 anytime 安全 chunk 或降级，而不是无限排队。
  4. **每请求 deadline + watchdog**：worker 超时→返回该端口上一安全 chunk 并记 DEGRADED；连续超时→标记端口 FAULT 并隔离；异常按请求捕获，绝不杀其他端口。
  5. **会话隔离**：每端口独立 `SessionState`（episode id、历史栈、先验、状态机、随机数）；后端函数显式接收 sess，禁止全局可变状态；单测断言两会话交错调用与独立运行逐位一致。
  6. **只读遥测**：每步延迟/动作统计/状态迁移写本地日志，赛后离线分析；评测期不做在线学习/适应。
  7. **故障注入**：worker 卡死、异常、OOM、端口断连、stale frame、坏动作；断言其余端口 p99 退化 < 20%。
- **与现有方案差异**：参考实现只给传输；本点补齐「多端口 = 多实例」的调度、隔离、故障语义。
- **技术可行性**：高（工程为主）。
- **所需资源**：2×A100 80G 共享后端；1–2 人周；1 台 CPU 压测机。
- **落地步骤**：①核实 N 与超时语义；②进程隔离基线；③共享后端 + 小窗口批处理；④N 客户端 soak + 故障注入；⑤真机 1–2 端口抽测；⑥按 N/内存选模式。
- **风险**：动态批处理放大尾部；共享后端显存/内存竞争；N 未知导致过度配置；状态隔离 bug 难测。

### I11 交互契约状态机 + 优雅降级（新） ★★★★★
- **动机**：契约刚性（F23）、交互质量可观测（F24）、闲置臂必须合法（F25）、无触觉/无心跳/超时语义未知。
- **设计**：
  1. **状态机**：`BOOT → HANDSHAKE → NOMINAL`；`NOMINAL → INTERFERED / STALE / DEGRADED`；`INTERFERED → RECOVERING → NOMINAL`；`DEGRADED → FAULT`。每状态定义允许动作集、转移条件、最小停留时间（防抖）。
  2. **anytime 兜底**：始终维护一个**不依赖模型**的 `safe_chunk`（保持当前位姿 / 收拢 / 减速），模型超时或异常时立即返回；保证合法、有限、限幅、平滑。
  3. **观测健康**：帧哈希 + 状态差分检测 stale/repeat；连续 k 帧陈旧→STALE（保持 + 降速）；恢复后首 chunk 降速。
  4. **人接近预测**：手部框中心/尺度/速度→到达工作空间时间估计；提前进入 INTERFERED；滞回避免振荡。
  5. **闲置臂 do-no-harm**：预标定 tuck pose；pivot 保持；夹爪保持；若任务切换臂，由状态机管理交接。
  6. **契约校验**：每个输出过本地 validator（`example_env` 规则 + 有限性/限幅/抖动上限）；CI 与运行时双保险。
  7. **交互质量指标**：接入 I8 v3。
- **与现有方案差异**：把「人手检测」从单点触发器升级为完整交互状态机；把「超时」从工程异常升级为契约内的可预期状态。
- **技术可行性**：高。
- **所需资源**：1 人周 + 真机标定。
- **落地步骤**：①状态机与安全动作集；②anytime 兜底；③stale/人接近检测；④闲置臂 tuck；⑤本地契约 CI；⑥真机干预/断线/stale 回放。

### 1.1 交互契约状态机 + anytime 兜底（I11）

```python
class InteractionPolicy:
    """T_a 在握手时冻结；运行期只改 chunk 内容与状态，不改 chunk 长度。"""
    def __init__(self, vla, T_a, tuck_pose, budget_ms):
        self.vla, self.T_a, self.budget_ms = vla, T_a, budget_ms
        self.tuck = tuck_pose
        self.state = "BOOT"
        self.stable = 0

    def get_action(self, obs):
        if self.state == "BOOT":
            self.state = "NOMINAL"

        # 1) 观测健康：陈旧/冻结帧
        if is_stale(obs) or is_frozen(obs):
            self.state = "STALE"
            return self.safe_chunk(obs, mode="hold")

        # 2) 人接近预测（带滞回）
        tta = hand_time_to_arrival(obs)          # 秒；无手返回 None
        if tta is not None and tta < T_YIELD:
            self.state = "INTERFERED"
        if self.state == "INTERFERED":
            if hand_clear(obs) and scene_stable(obs):
                self.stable += 1
                if self.stable >= K_STABLE:
                    self.state = "RECOVERING"
                    self.stable = 0
            else:
                self.stable = 0
            return self.safe_chunk(obs, mode="yield")   # 固定 T_a 的让位尾段
        if self.state == "RECOVERING":
            self.state = "NOMINAL"                        # 恢复首 chunk 降速
            return self.safe_chunk(obs, mode="resume")

        # 3) 标称推理 + deadline
        try:
            chunk = call_with_deadline(self.vla.propose_chunk, obs,
                                       timeout_ms=self.budget_ms)
        except (TimeoutError, ModelError):
            self.state = "DEGRADED"
            return self.safe_chunk(obs, mode="degraded")
        return self.guard(chunk, obs)   # 限幅/有限性/平滑/闲置臂 tuck

    def safe_chunk(self, obs, mode):
        # 不依赖模型：保持当前位姿或向 tuck 位姿做有界最小加加速度插值
        q_now = read_joints(obs)
        target = q_now if mode in ("hold", "yield") else self.tuck
        seq = min_jerk_interp(q_now, target, self.T_a, v_max, a_max)
        return pack_action(seq, gripper_hold(obs), pivot_hold(obs),
                           idle_arm="tuck")
```

> 注：Python 无法安全中断同步 CUDA 调用，`call_with_deadline` 必须在 worker/子进程层实现；主协程只负责「超时即放弃等待并走兜底」。
