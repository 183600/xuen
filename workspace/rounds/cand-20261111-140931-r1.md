# 第 54 轮（承接第 53 轮 v16 GroundEdge-GenSim++；灵感循环第 5 轮；本轮灵感：「动作空间」×「技能组合」×「云边协同」）

> 第 53 轮已把鲁棒性拆解为可传递的维度谱 ρ 与反向解释 Explain，形成可解释的鲁棒性金字塔。本轮聚焦 **动作空间剖面化、技能组合的可判定性、云边协同的闭环**。核心矛盾：H20：技能组合在动作空间上存在语义与时序错配，组合前看似兼容、执行时因动作空间交集/覆盖导致冲突；H21：云端全局规划与边端实时反馈在动作粒度上不一致，云端可用性证书在边端动作空间中失效。

## 0. 直觉与动机

**灵感 1（动作空间剖面 → 把技能从黑箱能力变为动作空间占用）**
直觉：技能 S 不只是一个鲁棒性谱 ρ_S，更是一个在动作空间 A 上的占用剖面 `α_S : A → [0,1]`。`α_S(a)=1` 表示动作 a 被技能完全覆盖，`0` 表示不可达。组合时，不是简单 `min(ρ)`，而是先做 **动作空间交集检查**：`A_{S1⊗S2} = A_{S1} ∩ A_{S2} ∪ transition(A_{S1},A_{S2})`。若交集为空或转换区 `ΔA` 超过边端可控带宽，则组合不可行。这样，**动作空间成为技能组合的第一性约束**，鲁棒性谱只在可行域内起作用。

**灵感 2（技能组合可判定化 → 从启发式拼接变为图搜索 + 证书）**
直觉：把技能库建模为 **动作空间有向图 G_S**，节点为技能，边为动作空间相容关系 `compat(S_i,S_j) = |A_i ∩ A_j| / |A_i ∪ A_j| ≥ θ_a` 且转换成本 `c_trans < τ_e`。组合规划变成在 G_S 上寻找满足任务动作序列 `A_T` 的路径，并为每条边附带 **组合证书 `C_comp = (A_overlap, ρ_comp, γ_ce)`**。这把组合从经验拼接变为可验证的路径搜索，并与第 53 轮的鲁棒性耦合矩阵 K 联动。

**灵感 3（云边协同 → 粗到细的动作分解与鲁棒性回传）**
直觉：云端负责 **粗动作空间 A_c** 的技能选择与组合序，边端负责 **细动作空间 A_e** 的实时追踪与鲁棒性校验。云端生成组合计划 `P_c = ⟨S_1,...,S_k; A_c⟩`，边端把计划映射为 `P_e = map(A_c→A_e)`，并用 TRO/REX 在线校验。若边端检测到 `ρ_e(d) < ρ_min` 或 Explain 返回根因 `a_e`，则通过 **反向解释信道** 回传给云端，云端触发动作空间重剖分 `reprofile(A_c)`。这形成 **云规划 - 边校验 - 反向解释 - 重剖分** 的闭环。

**灵感 4（动作空间对齐的耦合 → 鲁棒性 + 动作占用联合证书）**
直觉：组合后证书不应只记 ρ，还需记 **动作占用证书 `A_cert = (A_core, A_buffer, δ_a)`**，其中 `A_core` 为保证覆盖的核心动作子集，`A_buffer` 为容错带。云边协同时，云端承诺 `A_core ⊆ A_c`，边端保证 `A_core ⊆ A_e` 且 `ρ_e(A_core) ≥ ρ_min`。若云端扩张 `A_c` 超出边端 `A_e` 的物理带宽，则触发 `δ_a` 超预算否决。鲁棒性与动作空间在此耦合。

**灵感 5（从组合到协同的金字塔扩展）**
直觉：在第 53 轮鲁棒性金字塔 `𝕃` 之上叠加 **动作空间协同层 `𝔸`**：`𝔸_0` 物理动作极限，`𝔸_1` 技能动作剖面，`𝔸_2` 云边动作映射，`𝔸_3` 任务动作序列。跨层传递证书需同时包含 `ρ` 与 `A_cert`，形成 **可解释的动作-鲁棒性双证书体系**。

## 1. 形式化定义（增量：定义 115–120）

**定义 115（动作空间剖面）**
动作空间 `A = A_c × A_e`，`A_c` 为云端粗粒度动作，`A_e` 为边端细粒度动作。技能 `S` 的动作空间剖面 `α_S : A → [0,1]`，满足 `∫_A α_S(a) da = vol(S)`。**动作覆盖** `cover(S, A_T) = 1` 当且仅当 `∀ a∈A_T, α_S(a) ≥ θ_cov`。

**定义 116（动作空间兼容性）**
两技能 `S_i,S_j` 的动作兼容性 `compat(S_i,S_j) = |A_i ∩ A_j| / |A_i ∪ A_j|`。组合可判定条件：
```
compat(S_i,S_j) ≥ θ_a ∧ c_trans(A_i,A_j) ≤ τ_e ∧ ρ_{S_i⊗S_j}(d) ≥ ρ_min ∀ d
```
其中 `c_trans` 为动作转换成本，`τ_e` 为边端最大可控延迟。

**定义 117（技能组合图）**
技能组合图 `G_S = (V,E)`，`V` 为技能集合，`E = {(i,j) | compat(S_i,S_j)}`。每条边附带 **组合证书** `C_comp = (A_overlap, ρ_comp, γ_ce)`，其中 `γ_ce` 为云边映射函数 `γ_ce : A_c → A_e`。

**定义 118（云边协同契约）**
云边契约 `C_ce = (P_c, P_e, Δ, Explain_loop)`：
- `P_c` 云端组合计划：技能序列与粗动作序列；
- `P_e` 边端细化计划：`P_e = γ_ce(P_c)`；
- `Δ` 为动作空间对齐误差上界，`|A_c - γ_ce^{-1}(A_e)| ≤ Δ`；
- `Explain_loop` 为反向解释回传通道：`Explain(sim_e) → ΔP_c`。

**定义 119（动作空间对齐成本）**
对齐成本 `cost_align(S_i,S_j) = w_a·(1 - compat) + w_ρ·(1 - ρ_comp) + w_ce·||γ_ce - id||`。组合搜索目标为最小化路径总成本。

**定义 120（云边鲁棒性动作联合证书）**
联合证书 `J = (ρ, A_cert, γ_ce, δ_a, evidence)`：
- `ρ` 为第 53 轮鲁棒性谱；
- `A_cert = (A_core, A_buffer, δ_a)` 为动作占用证书；
- `γ_ce` 为云边映射；
- `δ_a` 为动作对齐容差；
- `evidence` 至少包含边端仿真反例与云端规划日志。若 `dom_J(T)=in` 且 `δ_a < Θ_a`，则组合可部署。

## 2. 关键算法 伪代码

### IP-115 ACS（Action Space Characterization）

```python
def action_profile(skill, A_c, A_e):
    alpha = {}
    for a_c in A_c:
        for a_e in A_e:
            feas = skill.can_execute(a_c, a_e)
            alpha[(a_c,a_e)] = 1.0 if feas else 0.0
    return alpha

def cover_check(alpha, A_T, theta_cov=0.8):
    return all(alpha.get(a,0) >= theta_cov for a in A_T)
```

### IP-116 SCOM（Skill Composition Graph）

```python
def build_composition_graph(skills, theta_a, tau_e):
    G = nx.DiGraph()
    for i,s1 in enumerate(skills):
        for j,s2 in enumerate(skills):
            if i==j: continue
            compat = jaccard(action_profile(s1), action_profile(s2))
            c_trans = transition_cost(s1, s2)
            if compat >= theta_a and c_trans <= tau_e:
                rho_comp = compose_robustness(s1.rho, s2.rho, K)
                G.add_edge(i,j, compat=compat, cost=c_trans, rho_comp=rho_comp)
    return G
```

def cloud_plan(T, G, A_c):

def edge_refine(P_c, gamma_ce, sim_model):
    P_e = []

## 6. 本轮最大风险

**一句话**：动作空间剖面化与云边协同把技能组合从“能力匹配”提升为“动作-鲁棒性双证书”，但其 soundness **三重依赖动作剖面的完备采样、γ_ce 映射的单调可逆、以及 Explain 回传的实时收敛**；一旦动作剖面欠采样导致虚假兼容、或云边映射在极限动作处非单调，组合路径在真实边端会系统性动作错位并触发负迁移，故必须以 **主动剖面采样 + Lipschitz 约束的 γ_ce + 负迁移绊线** 三重护栏，宁可保守组合，绝不把动作空间的“可对齐假象”当作部署前提。

# 第 55 轮产物 · 创新点清单 v32：GroundEdge-GenSim+++L（IGC×SRC×SSL×ACS-D×JCL×PAR）

> 承接第 54 轮产物 v31。本轮把"语言指令"与"数据规模"两个被默认掉的假设显式化为一级公民，在动作-鲁棒性双证书 `J` 之上叠加**语言接地证书 `G_cert`**与**统计半径 `ε(n,δ)`**，形成三证书体系 `J^L`：
> - **IGC（Instruction Grounding Compiler）**：把指令编译为受约束动作 `A_T`、硬约束 `C`、自由维度 `U` 与欠定度 `u`；

> - **ACS-D（Active Certificate Sampling with Data）**：由证书自身驱动的定向采样；
> - **JCL（Joint Language Certificate）**：合并 `J` 与 `G_cert` 的部署判定；
> - **PAR（Paraphrase Adversarial Robustness）**：用释义扰动测接地不变性 `ρ_lang`。

> IP 编号：IP-121~IP-126（共 6 个新增），升级 IP-115/116/118 以纳入指令与样本预算维度。核心立场：**证书不是真值，而是"在 n 个样本、δ 置信、u 欠定下的有界断言"**。

### IP-122 SRC

```python
def required_n(eps, delta, n_cells):
    return n_cells * math.ceil(math.log(2*n_cells/delta) / (2*eps**2))

def certificate_radius(n, delta, n_cells):
    per_cell = max(n / n_cells, 1.0)
    return math.sqrt(math.log(2*n_cells/delta) / (2*per_cell))

def certify(n, delta, n_cells, eps_tol):
    eps = certificate_radius(n, delta, n_cells)
    return ('ok' if eps <= eps_tol else 'underpowered', eps)
```

### IP-123 SSL

```python
def fit_saturation(ns, succs, p0, eps_tol):
    c, alpha, u = nonlinear_fit(ns, succs, model='capped_power')
    S_inf = 1 - u*(1-p0)
    n_star = (c/eps_tol)**(1/alpha) if alpha > 0 else float('inf')
    return Saturation(S_inf, c, alpha, u, n_star)

def falsifies(S, ns, succs, slope_tol):
    tail = [(n,s) for n,s in zip(ns,succs) if n > S.n_star]
    return slope(tail) > slope_tol or not monotone_decreasing_by_u(S)
```

### IP-124 ACS-D

```python
def active_batch(Ls, cells, budget, var_hat, w_task, Gs, lam=1.0):
    scored = []
    for L in Ls:
        U = Gs[L].U
        for a in cells:
            scored.append((var_hat[a]*w_task[a]*(1+lam*(a in U)), L, a))
    scored.sort(key=lambda t: t[0], reverse=True)
    return dedup([(L,a) for _,L,a in scored])[:budget]
```

### IP-125 JCL

def joint_language_certificate(J, G, n_A, delta_J, n_g, delta_g,
                               eps_tol, theta_u, theta_lang):

def paraphrase_robustness(L, grounder, paraphraser, k=20):
    base = grounder(L)
    agree = sum(compatible(base, grounder(Lp), tol=0.1)
                for Lp in paraphraser.sample(L, k))

## 3. 数值示例：为什么"数据规模"必须写成半径

取 `|A|=1000` 个动作单元、置信 `δ=0.05`：

| 目标半径 ε | 每单元样本 `n_a` | 总样本 `n` |
|---|---|---|
| 0.10 | `ln(2·1000/0.05)/(2·0.01) ≈ 530` | `≈ 5.3×10^5` |
| 0.05 | `≈ 2119` | `≈ 2.12×10^6` |
| 0.02 | `≈ 13241` | `≈ 1.32×10^7` |

结论：要把 `ε` 减半，总样本约增 `4×`（`ε^{-2}`），且并集校正带来 `ln|A|` 的隐性乘子。这解释了为什么"再多采一点数据"在单元数大时昂贵——也说明**分层置信分配**（把 `δ` 优先给任务核心动作 `A_core`）比全局均匀更划算。

饱和律数值示例：取 `u=0.20, p0=0.50`，则 `S_∞=1-0.2·0.5=0.90`。即使 `n→∞`，成功率也只能到 90%，剩余 10% 由"指令没说清、默认策略又不擅长"的自由度决定。**这 10% 是任何数据规模都买不回来的**。

## 5. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| IGC | O(parse(L)) | O(|A|) | 解析覆盖完整，U 可测 |
| SRC | O(1) 计算 / O(n) 采样 | O(n_cells) | Hoeffding + 并集校正 |
| SSL | O(#n·iter) | O(#n) | 幂律可辨识，平台有下界 |
| ACS-D | O(|L|·|A| log(|L|·|A|)) | O(budget) | 采集函数非退化，去重 |
| JCL | O(|A_core|) | O(1) | δ_total 并集闭合，ε 阈值 sound |
| PAR | O(k·parse(L)) | O(k) | 释义语义保持性（A30） |

**正确性定理（Language-Grounded Data-Scaled Soundness）**
设 (A22)–(A28) 成立，且 **(A29)** 每动作单元样本独立同分布；**(A30)** 释义为语义保持变换；**(A31)** `p0` 有下界估计。则对任一通过 JCL 的 `J^L`：
```
P(task success) ≥ [1 - Σ_d(1-ρ_min(d)) - β_E - P(δ_a>Θ_a)]
                 · [1 - u·(1-p0)]
                 - ε(n_A,δ_J) - (1-ρ_lang)
```
且 `n_A ≥ n* ⇒ ∂succ/∂n < ε_tol`。这里 `[1-u(1-p0)]` 是**语言侧不可约上限**，`ε` 是**数据侧可约误差**，`(1-ρ_lang)` 是**接地侧稳定性误差**——三者相乘/相减，正好对应"语言 × 数据 × 语义不变性"三根支柱。

## 7. 本轮最大风险

**一句话**：本轮把"语言欠定度封顶数据收益"写成可证伪的饱和律，但 `u、ρ_lang、n*` 全部是从有限且长尾的指令分布上估计的——一旦真实指令落在长尾 OOD 区，经验 `n*` 会系统性低估、`G_cert` 会对未见释义过度自信，联合证书看似同时满足统计与接地条件，实则在分布外指令上把"数据规模堆出的假天花板"当作部署保证；故必须以**留出释义族 + 分布漂移拒答 + 平台下界置信带**三重护栏，宁可对长尾指令拒答，也不把经验饱和点当作分布的饱和点。
