## 1. 两个灵感的第一性原理

### 灵感 1 ·「演示方案」→ 演示是唯一「全栈同时在线」的验收测试

**直觉解释**：实验室里每个模块单独都能过；只有当检测器、状态层、伺服、介入、网络传输同时在一个真实时延预算里跑，集成故障才会现形。演示（一次成片、外部可观察）就是这种压力测试，也是最难被 cherry-pick 的证据。

**严谨化**：

- **长程放大**：把「每步出现一次非灾难性集成故障」看成强度 λ 的稀疏事件，长度 N 的单镜成功率 `Y(N) ≈ e^{−λN}`（L14）。N=1000 时，λ 只要 `2.2×10⁻⁴/步`（约每 4500 步一次）就能把 Y 压到 0.8；短测 N≈50 时同样的 Y 允许 λ 宽 20 倍——**短测通过不蕴含长演示通过**。
- **不可挑选**：one-take 规则消灭「cut 到成功片段」；脚本必须预注册，并留出未排练种子（holdout script），防止把 take-rate 变成「排练次数」的函数。
- **契约而非表演**：演示方案 = `(脚本, take 预算, 时延预算, 覆盖矩阵, 验收谓词)`（U19）；每次失败必须能归因到模块（U21），否则记为「不可归因失败」并阻断验收。
- **叙事资产**：runs 页将公开「完整评测视频」→ 视频是否看得懂，决定评审/用户能否看见我们的护城河。故把**可读性纳入正确性**（P15）。

**策略含义**：v3 的栈解决「内部正确」；演示回路回答「放在一起是否仍然正确、且看起来正确」。

### 灵感 2 ·「用户测试」→ 用户既是干扰源，也是评测者

**直觉解释**：真实用户不会按泊松分布捣乱——他们会在机器人最脆弱时连续遮挡、搬走目标、甚至去碰它。把用户请进来，一次拿到两类信息：真实干扰先验 + 可读性/信任。

**严谨化**：

- **干扰源**：用户测试把 U18 的四类干扰从「合成手部贴图」变成「真人事件流」。真实到达过程常过散（`c_v² > 1`，成串出现）；L12 的「保持占优」若只用均值等待时间评估，会**期望上划算、尾部上翻车**。改用高分位/CVaR 评估，并设最大保持步数/重试上限（L15）。
- **评测者**：让留出标注者只看「运行视频 + 状态层日志摘要」，测归因正确率与时延（U21）；再把用户主观信任与客观成功率做校准（理想斜率≈1）。
- **朴素操作者**：非专家会带来不同机位、少相机、不同光照——正对上 F5 的 2 相机数据，是「腕部→头部」滑移检测回退的天然压力测试。

**策略含义**：用户测试同时关闭 Q12 的「合成→真实」缺口，并为演示提供盲测评审；二者合成一个回路，而不是两场表演。

## 2. 研究问题（新增 Q13–Q15，接第 1–3 轮 Q1–Q12）

- **Q13（演示集成与 take-rate）**：全栈在长程任务上、时延预算内的一次成片成功率是多少？失败中「集成故障」与「能力不足」各占多少？（E634 / E635）
- **Q14（真实用户干扰）**：真人干扰的到达/突发性与合成分布差多少？「保持」策略在过散到达下何时仍占优（L12 的高分位版本，L15）？（E636）
- **Q15（可读性与信任）**：留出评审者能否在限定时间内把失败归因到正确模块？用户信任能否校准到真实可靠性？（E637）

## 3. 设计原则（新增 P13–P15，接第 1–3 轮 P1–P12）

- **P13（演示即集成真值）**：任何模块不得只凭单元实验上线，必须通过单镜演示门（IP-16）；在单镜中消失的单元增益记为集成债，不计入成绩。
- **P14（用户是干扰先验）**：干扰阈值与协议以真实用户日志为准，合成数据只做回归；真实到达过散时按高分位而非均值做安全决策。
- **P15（可读性即正确性的一部分）**：每次失败必须能在限定时间内从「视频 + 日志摘要」归因；不可归因 = 不可修复 = 不可验收。

## 6. 本轮最大风险

一句话：**演示过拟合**——如果脚本被反复排练到只走成功路径，take-rate 就会变成「排练次数」的函数而不是系统可靠性的函数，我们会用一场漂亮的单镜表演，掩盖长程与真实干扰下的脆弱；对冲是脚本预注册 + 未排练种子留出 + 按功效设 take 预算（L16）+ 用户盲测 + 在演示中强制注入干扰。

## 3. 新增 IP 详述

### IP-16 · DemoContract / DemoBench 单镜演示契约（P0，新）

- **动机**：前三轮的实验都是「分模块、可中断、可挑选」的；集成故障（时延叠加、状态层卡顿、chunk 边界、日志/序列化）只在全栈同时在线时出现。演示是唯一「一次成片、外部可观察」的验收测试，也是公开评测视频（F2）的天然形态。
- **与现有方案差异**：不是「拍个 demo 视频」，而是把演示写成可预注册的契约（U19）：脚本含泛化轴与干扰注入，take 预算按功效（L16）提前定，失败必须归因（U21），否则判为不可验收。与 IP-06 的分工：IP-06 管「能力诊断」，IP-16 管「集成真值」。

## 6. 关键算法骨架（新增片段；主体沿第 1–3 轮 `UniBotSAGEPolicy`）

```python
# ===== IP-16: 单镜演示（one-take，全栈在线，禁 cut）=====
class DemoRunner:
    def __init__(self, script, take_budget, p99_budget, tar):
        self.script, self.N = script, take_budget      # N 由 L16 功效计算预注册
        self.p99_budget, self.tar = p99_budget, tar

    def take(self):
        log, t0 = [], now()
        for k, obs in enumerate(self.env.rollout(self.script)):   # 一次成片
            act, meta = self.policy.act(obs)                      # 全栈同时在线
            log.append((k, meta, now() - t0))
            self.env.step(act)                                    # 不允许 cut/重来
        return {"success": self.env.done,
                "p99": p99([l[2] for l in log]),
                "attribution": attribute(log, self.env.fail_stage)}

    def gate(self, holdout):
        res = [self.take() for _ in range(self.N)]
        take_rate = mean(r["success"] for r in res)
        unattributed = sum(r["attribution"] is None for r in res)
        if take_rate < TAU_DEMO:      return "LOG_ONLY"   # 不得作为证据
        if unattributed > 0:          return "BLOCK"      # 先补日志 schema
        if max(r["p99"] for r in res) > self.p99_budget: return "SHAPE_LATENCY"
        return "PASS"
```

## 7. 推导（新增引理 L14–L16；L1–L13 沿用第 1–3 轮）

**引理 L14（长程 take-rate 的指数放大）** 把「每步出现一次非灾难性集成故障」建模为强度 λ 的稀疏泊松事件，长度 N 的单镜成功率 `Y(N) ≈ e^{−λN}`。于是 `∂lnY/∂λ = −N`：成功率对每步故障率的敏感度随长度线性增长；给定验收 τ，允许 `λ* = −ln τ / N`。N=1000、τ=0.8 ⇒ `λ* ≈ 2.2×10⁻⁴/步`（约每 4500 步至多 1 次）；N=50 时同一 τ 放宽 20 倍。⇒ **长程演示是「低强度集成故障」的放大镜，短测通过不蕴含长演示通过**；且故障成串（L15）只会更糟。∎

**引理 L15（过散干扰下「保持」须按高分位评估）** 设真实干扰到达为更新过程，间隔均值 μ、方差 σ²、`c_v²=σ²/μ²`。L12 的保持占优条件 `h < C_r + Δ` 若用 `E[h]=μ` 评估，隐含 `c_v²=1`。当 `c_v²>1` 时等待时间右尾更厚，恢复窗口内再次受扰的概率高于同均值泊松；期望上划算的方案可在尾部翻车。故把条件改为 `CVaR_θ(h) < C_r_completed + Δ`，并设最大保持步数/重试上限 K，超限转重定位或重启。⇒ **c_v² 越大，可安全「保持」的场景越少**；这正是 E636 要估计的量。∎

**引理 L16（演示/用户测试的样本量与功效）** 单臂估计成功率 p、半宽 w、置信 1−α：`T ≈ z_{1−α/2}²·p(1−p)/w²`。例：p=0.5、w=0.1 ⇒ T≈96；w=0.2 ⇒ T≈24。双臂比较 p₁、p₂、差 Δ：`T_arm ≈ (z_{1−α/2}+z_{1−β})²·[p₁(1−p₁)+p₂(1−p₂)]/Δ²`。例：p₁=0.5、p₂=0.6、Δ=0.1、power=0.8 ⇒ 约 385 take/臂。⇒ **take 预算必须先按功效预注册；「20 次 take 赢 3 次」在统计上与噪声不可分**，不得作为验收证据。∎
