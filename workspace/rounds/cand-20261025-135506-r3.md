# 第 8 轮 · RC-VLA：把评分表编译成「步骤对齐 + 字典序自评」，用单模型规则反向裁剪方案

> 注：本轮是灵感循环的第 3 轮（灵感词：单模型多任务/奖励设计/创新点提炼）；为保持文件跨轮连续编号，标记为第 8 轮。

> 检索/复核日期：2026-10-25（UTC）。赛事身份不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API。本轮三个灵感词是「单模型多任务」「奖励设计」「创新点提炼」。我先去读官方参赛手册，结果发现上一轮有两个硬错误：**排行榜是成功率优先的字典序，步骤分只在平局时用**；而「终局放置是闸门」只是潜变量难度模型的一个特例，不是普遍规律。改正之后，13 个组件被压到 6 个，主线变成一句话：**公开评分表本身就是免费的多任务监督——用 CTC 把 33k 条无标注演示对齐到步骤文本，训练一个与排行榜同序的 soft-min 自评头，在同一个 checkpoint 内做 chunk 重排与恢复。**

## 0. 本轮核实：六个会改策略的事实

### 0.1 排行榜是字典序，不是加权和（最重要）

中文手册原文：「实时榜单按 32 个任务的**总平均成功率**进行排序，成功率相同时按**总平均步骤分**排序，若仍相同，则**提交日期较早**的模型排序靠前。」英文版同义（[S1][S2]）。这直接推翻上一轮的收益算法：

```text
上一轮假设：rank ≈ α·success + β·step_score      （加权和）
手册实际：  rank_key = (avg_success, avg_step_score, -submission_time)  （字典序）
```

含义有四条：

1. **成功率是唯一主目标**；步骤分不是「大头收益」，而是①密集训练信号、②平局裁决、③归因诊断。
2. 「终局放置 +Δ ⇒ 总分 +Δ×q」的杠杆表不成立；那只在加权和假设下成立。
3. 不要用「部分分最大化」替代「整条任务成功」。一个稳定 3/4 步、但从不收尾的策略，成功率是 0，步骤分再高也排在所有能完成的人后面。
4. 平局不是小概率：总平均成功率是 1/320 的倍数，队伍一多就会出现并列；**早提交是真实的平局优势**，这对提交节奏是战略信息。

### 0.2 单模型是硬约束，而且比「一个 checkpoint」更严

手册：「所有任务须基于**同一模型**完成，**不得混合使用多个模型**一起进行测试，但对模型类型不作限制（World Model、VLA 均可）。」[S1][S2]

严格读法：推理时必须只有一个模型。外挂 SAM 检测器、独立 reward model、独立 world model、每任务 LoRA/模型合并，都可能被认定为「混合多个模型」。这条规则一次性杀掉了上一轮的四个组件：

- **PGL**：需要 SAM 类检测器 + 锚点渲染 → 第二模型风险 + 域差；
- **OPT**：需要容器 6D 位姿估计器 → 第二模型风险 + 透明/布料失效；
- **ICR**：需要独立检索编码器 → 第二模型风险 + 延迟；
- **DreamSteer 式 world model + value model**：两个额外模型 + 13s/次的重排延迟 [S11]。

反过来，它把设计推向一个很清晰的形态：**一个 checkpoint + 多个头 + 确定性代码**。确定性代码（步骤编译器、脚本原语、时间守卫、谓词检查）不是模型；所有学习组件必须共享同一个 trunk。这也正是我们与 SARM2 / RoboReward 的关键差异——它们用独立 reward model，我们只能做「自评头」[S14][S15]。

### 0.3 每任务 10 次，5 类泛化各 2 次

手册：「每个任务执行 10 次独立运行……10 次运行中包含以下 5 种泛化类型，每种类型各出现 2 次。」[S1][S2]

这条给了我本轮最冷的一盆水：

- 单任务 10 次运行，3/10 成功的 Wilson 95% CI = **[10.8%, 60.3%]**；
- 全榜 32×10=320 episodes，总体 SE ≈ **2.56pp**；+5pp 只有 z≈1.95（约 50% 功效），+10pp 才 z≈3.90；
- 上一轮「调试槽 +10pp 作为发布门」在统计上几乎不可行：10 次运行检测 +10pp 的功效只有 **16.6%**（需 ≥6/10）；要 80% 功效需 ~136 次/任务。
- 占位榜相邻名次全部小于 1 SE：29.7→28.5 是 0.47 SE，28.5→27.9 是 0.23 SE，前 3 名统计上不可分。

推论：**只押广谱、≥10pp 的改进；不要为 2–3pp 的离线提升改架构；不要按单任务调试结果调参。** 调试槽的正确用途是定性失败分析和大效应验证，不是精细 A/B。早提交拿平局优势。

### 0.4 演示数据没有步骤标注

HangCup 的 `meta/info.json`（HF raw，2026-10-25）里，features 只有 4 路视频、双臂关节/EE 位姿（base/torso 两套）、夹爪、lower body、timestamp/frame_index/episode_index/task_index；**没有 subtask、step、progress、success 字段**（[S4]）。这意味着：

- 官方 `score_steps` 不能直接当训练标签；33k 条演示是「只有终局成功、没有过程标签」的弱监督。
- 但每条演示的**步骤文本序列是已知的**（`info.json` 的 `score_steps` 按顺序给出，且每条指令有 5 条英文复述，[S5]）。这是一份天然的「转录稿」（transcript）。
- 于是问题变成 forced alignment：**无标注帧序列 + 有序步骤文本 → 每帧的步骤标签**。CTC/ECTC 正是为此设计的（[S17][S18][S19]）。

这是本轮的技术支点：**不用人工标一步，用评分表把 33k 条演示变成免费的密集步骤标签。**

### 0.5 榜单/运行记录仍是占位，且「Live」标签与数据来源矛盾

- `leaderboard_data.json` 仍写 `"generated_from": "gen_leaderboard.py"`，发布时间 2026-10-08；8 个模型 × 32 任务 = 256 条 task_metrics 是脚本生成（[S6]）。
- `runs.html` 仍是 `256 / 256`，页面底部「即将发布」；详情页此前明确写「测试视频占位」（[S7]）。
- 但 `leaderboard.html` 现在顶部写「Ranking · Live」——这是前端文案，不是数据真实性的证据。

结论：**8 个模型的数字只能当界面占位，不能当难度先验、不能当基线、不能用来推断轴级瓶颈。** 上一轮把「步骤分 − 成功率 ≈ +8.6pp」当弱先验，本轮删除。

### 0.6 官方底座与数据规模

- UniFoLM-WLA-1.0：6B，64 任务，约 2,500h 真机数据，Apache-2.0，支持 LoRA/全量微调（[S8]）。
- UniBot 数据：32 个数据集，每个 969–1,530 条，合计约 33k、169h；HangCup 1,043 条 / 194,564 帧 / 30fps，lastModified 2026-10-14（[S3][S4]）。
- 现实约束：33k 条 / 169h 对 6B 模型是「小数据」；单一 checkpoint 要在 32 任务上共享，必须靠**更好的标签与条件化**，而不是每任务堆参数。

## 1. 两个纠正（本轮最重要的思考）

### 1.1 纠正一：不是「步骤分是大头」，而是「成功率是主目标，步骤分是平局与诊断」

上一轮的杠杆表是这样的：

```text
单轴成功率 +Δ          → 该轴（1/5 权重） → +Δ/5
终局放置成功率 +Δ      → 所有轴           → ≈ +Δ×q
```

它在「成功率与步骤分加权综合」的假设下成立。但手册是字典序，正确的收益函数是：

```text
rank_key = (avg_success, avg_step_score, -submission_time)
```

所以：

- 任何「提高部分分但不提高整条成功率」的改动，只在平局时有用；
- 任何「提高整条成功率」的改动，即使步骤分不变，也直接提升排名；
- 步骤分的正确用途是三个：① 密集训练信号（比 0/1 成功更好学）；② 平局裁决（真实存在）；③ **归因诊断**（见 1.2）。

这也意味着：**不要为了「多完成一步」而牺牲「偶尔整条完成」**。例如，一个策略为了稳妥只做前 3 步、从不尝试最后一步，它的成功率是 0，步骤分再高也排在所有能完成的人后面。

### 1.2 纠正二：「终局放置是闸门」只是潜变量模型的一个特例

我一开始想证明占位榜「算术上不可能」：假设步骤独立，给定步骤分 39.0，2 步任务的最高成功率是 0.39² = 15.2%，而榜单写 29.7%——看起来矛盾。但这个推导**错在假设了步骤独立**。正确的约束是 Fréchet / 潜变量模型：

```text
设 episode 难度 d ~ U(0,1)，步骤 i 成功 iff d ≤ q_i（单调阈值）
则：P(step i) = q_i
    success    = min_i q_i = p
    step_score = Σ w_i q_i  = s
定义「其余步骤相对容易度」 E = (s − p) / (1 − p) ∈ [0,1]
  E → 0          ：所有步骤一样难（平坦 / 共同因子）
  E → 1 − w_term ：只有终端步难，前序全过（终端瓶颈）
```

占位榜 8 条 runs 抽查：E = 0.063–0.224；榜首整体 E = 0.132。若终端是唯一瓶颈，2 步任务应有 E≈0.50、3 步 0.60、4 步 0.75。实测远低于此——**如果这些数字是真的，难度是「共同因子」型的，不是「终局放置」型的**。但它们是占位数据，所以这不是结论，而是**方法**：真实 runs 出来后，先用这个反演判断该攻「最弱一步」还是「共同能力」。

这个反演还给出一个可证伪的预测：在单调模型下，`success = 最难一步的边际成功率`；提高更容易的步骤只改善步骤分（平局），不改善成功率。若真实数据 E 很小，则「终局放置专项」是低杠杆，应该攻 grasp / perception / 语言 grounding 这类共同因子。

我保留「终端步是必要事件」这个事实（success = 全步骤完成），但不再把它当成「终端步是瓶颈」的证据。**必要 ≠ 瓶颈。**

### 1.3 这两个纠正如何改变预算

上一轮：放置专项 40%、恢复 20%、数据/孪生 20%、工程 20%。

本轮：**测量与标签 30%（RTA + RID）、自评与重排 40%（LRC + CVR）、失败合成 15%（FSS）、工程/合规 15%**。砍掉孪生与外部数据，省下的算力转到「把 33k 演示的步骤标签做准」和「把自评头做准」。

## 2. 三个灵感词各自的落点

### 2.1 单模型多任务：不能按任务切模型，只能在一个 checkpoint 内做条件计算

- 规则禁止「混合多个模型」，所以「每任务一个 LoRA / 一个 head model / 一个检测器」都不安全。
- 32 个任务的步骤文本天然给出一个共享的**技能词表**（grab/place/stack/insert/close/zip/pour/fold/pick/hang/flip/lock…）。把步骤文本映射到 ~12 个技能 token，actor 与 critic 都条件化在 (skill, step index, object) 上。
- 这不是「任务 ID 条件化」，而是「技能条件化」：同一技能在不同任务间共享数据，未见任务只要拆成已知技能就能组合。它是**单模型内的 specialization**，不是多模型。
- 预期收益：33k 条演示在技能层池化，缓解 32 任务数据不均（969–1,530 条/任务）与负迁移；critic 的步骤分类也有共享标签空间。
- 可证伪：skill-token vs task-token vs none 的 held-out 步骤对齐准确率与终局成功率；若 skill-token 不优于 task-token，砍掉。

### 2.2 奖励设计：评分表是 reward machine，但排序是字典序，所以 critic 也必须是字典序

形式化：`RM = (S, s0, δ, r)`，S = 步骤，δ = 谓词完成事件，r = 步骤权重。一次 episode 的 return = Σ w_i·1[step i done] = 步骤分；success = 1[到达终态]。

排行榜的排序不是 return 的期望，而是 `(P(success), E[return])` 的字典序。所以自评头必须有两个层次：

```text
主头：P(success | state, instruction)
      在单调模型下 P(success) = min_i P(step i)
      用 soft-min 聚合每步完成概率，得到稠密、可微的成功代理：
      V_succ = −τ log Σ_i exp(−p_i/τ)
次头：E[step score] = Σ w_i p_i      # 只用于平局与诊断
重排：先按 ΔV_succ 排，再按 ΔV_step 排  # 与榜单同序
```

为什么不用「加权和」当主目标：加权和会被「容易的前几步」主导，鼓励策略停在 3/4 步；soft-min 直接盯最难一步，和 success 的瓶颈结构一致。

奖励塑形：用 potential-based shaping，Φ = V_succ，`R' = R + γΦ(s') − Φ(s)`，不改变最优策略；避免 critic 学会「看起来像进步」的 hack。

训练标签的三个来源：

1. **CTC 对齐**给出每帧的步骤后验与边界；边界前后给出「步骤完成」的正负样本；
2. **FSS**（官方 human 剧本 + 反事实）给出失败/撤销样本；
3. **跨 episode 目标互换**给出 goal-conditioned 负样本（同一观测、换一个目标 → success=0）。

### 2.3 创新点提炼：13 → 6，砍掉「外挂模块」和「终端放置」的普适性

- **保留并升级**：SSG → RTA（步骤对齐）、SVL → LRC 的验证/恢复、NRB → FSS（官方 human 剧本）、GPR-VLA → RC-VLA（单 checkpoint 三头）。
- **新增**：RID（评分反演诊断）、STC（技能 token）、NAP（噪声感知评测协议）。
- **砍掉**：PGL（外挂 SAM + 锚点渲染）、OPT（容器位姿估计 + 放置位姿迁移）、ICR（独立检索编码器 + 延迟）、TCLB/全孪生、L2L 主线、每任务 LoRA、world model rollout、FLEET 研究轴。

砍的理由不是「不好」，而是四条：

1. 违反单模型严格读法（PGL/OPT/ICR/world model 都需要第二模型）；
2. 与「共同因子」假设不匹配（终端放置专项可能是低杠杆）；
3. 10 次/任务的噪声使 2–3pp 的小增益不可测；
4. 33k 数据没有步骤标签，**先把标签做出来比堆模块更划算**。

## 3. 蒸馏后的主线：RC-VLA（Rubric-Critic VLA）

```text
language(160 复述之一) ──► 确定性 Rubric 编译器 ──► 步骤图 (s0..sk, w_i, skill tokens)
                                 │
obs(4 相机 + proprio) ──► 共享 6B trunk ──┬─► Actor head (flow) ──► K 个候选 chunk
                                           ├─► RTA head (CTC) ──► 每帧步骤后验/边界
                                           ├─► Step heads ──► p_i(step done)
                                           └─► Chunk-value head Q(s, chunk) ──► ΔV_succ
                                 │
                    字典序重排：max ΔV_succ，再 max ΔV_step
                                 │
                    执行 chunk → 监测 V_succ 停滞/回退 → 恢复（重试/重抓/重放）
```

- **一个 checkpoint**：trunk + actor + RTA + step heads + Q head；无外挂模型。
- **三个用途**：RTA 产标签（训练）、LRC 做重排与恢复（推理）、RID 做预算分配（赛前/赛后诊断）。
- **与上一轮的区别**：没有 PGL/OPT/ICR，没有孪生，没有 per-task LoRA；所有学习组件在同一 checkpoint 内。

## 4. 为什么这比上一轮的 PILOT 更该做

1. **合规**：严格单模型读法下，PILOT 的 PGL/OPT/ICR 都有「第二模型」风险；RC-VLA 没有。
2. **对齐排序**：PILOT 优化步骤分；RC-VLA 优化 P(success)（soft-min），步骤分只做次目标。
3. **对齐数据**：PILOT 假设有步骤标签/容器位姿；RC-VLA 用 CTC 从无标注演示里造标签，零人工。
4. **对齐噪声**：PILOT 的「调试槽 +10pp 发布门」功效只有 17%；RC-VLA 明确只押 ≥10pp 的广谱改进，并用离线步骤级指标做日常迭代。

## 5. 风险与证伪（本轮先立后破）

- **RTA 对齐质量**：抽 100 条人工检查边界；若边界误差 > episode 时长的 10%，退回「夹爪事件 + 步骤顺序」分段。停止条件：CTC 后验熵在边界处不降。
- **Critic 排序准确率**：离线构造 (chunk+, chunk−) 对，若 top-1 选择准确率 <60%，砍掉 CVR，只保留 LRC 做验证/恢复。
- **候选多样性**：K 个采样若几乎相同，重排无增益；用温度采样 + 脚本原语（移动/开合夹爪）扩充候选；脚本原语是确定性代码，不算模型。
- **延迟**：K=4、2Hz、6B、4 相机，p99 <500ms；若超，K=2 或改成「单 chunk + critic 触发重规划」。
- **单模型审计**：所有头在同一 checkpoint；推理路径无外部模型；模型卡写清。
- **占位数据**：不用；等真实 runs 出来再跑 RID。
- **统计噪声**：不追 <5pp；调试槽只做定性/大效应；早提交拿平局优势。

## 6. 一句话押注

**把公开评分表编译成同一 checkpoint 内的「CTC 步骤对齐头 + 字典序 soft-min 自评头」：前者把 33k 条无标注演示变成免费密集监督，后者直接优化「最难一步」并用 chunk 重排兑现成整条成功率——这是唯一同时满足单模型规则、成功优先排序和 10 次/任务噪声约束的杠杆。**

# 第 8 轮产物区 · RC-VLA 技术报告（Rubric-Critic VLA：单 checkpoint 内的步骤对齐与字典序自评）

> 目标赛事：宇树科技 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署、官方远程真机 API 评测。检索/复核日期：**2026-10-25（UTC）**。本报告在第 7 轮 PILOT-GPR 基础上做**纠错 + 蒸馏**：删除「步骤分是大头」的加权和假设，删除需要第二模型的 PGL/OPT/ICR，把 13 个组件压到 6 个。**最重要的新事实：排行榜按平均成功率排序，步骤分只在平局时使用；单模型规则禁止混用多个模型；每任务固定 10 次（5 类泛化 × 2）。**

## 0. 产物摘要

### 0.1 一句话

**把公开评分表编译成同一 checkpoint 内的「CTC 步骤对齐头 + 字典序 soft-min 自评头」：RTA 把 33k 条无标注演示变成免费密集步骤监督，LRC 直接优化「最难一步」并用 chunk 重排兑现成整条成功率；外挂检测器/独立奖励模型/世界模型全部删除，以满足单模型规则。**

### 0.2 组件与是否进推理

| 组件 | 作用 | 进推理？ | 是否学习 |
|---|---|---|---|
| RC 编译器 | 语言→任务→步骤图（官方 `score_steps` + 5 复述） | 是（确定性代码） | 否 |

### 0.3 预期收益（可证伪）

- 若 RTA 边界误差 <10% episode 时长，且 LRC 的离线 chunk 排序准确率 >60%，则 CVR 的离线终局成功率目标 **+5~10pp**；在线只押 **≥10pp** 的广谱改进（10 次/任务的噪声决定）。
- 若 RID 显示 E<0.25（平坦/共同因子），则预算从「终端放置专项」转向「grasp/perception/语言 grounding 的共同鲁棒性」；若 E>0.5，才恢复终端专项。
- **可证伪点**：离线 top-1 排序准确率 <60%，或 RTA 边界误差 >10%，则 CVR/RTA 不成立，退回「单纯 BC + 失败分析」，不提交该版本。

## 1. 事实核对（本轮新增，全部一手；来源表见 §13）

### 1.1 官方排序规则：字典序

中文手册原文（[S1]）：

> 「实时榜单按 32 个任务的**总平均成功率**进行排序，成功率相同时按**总平均步骤分**排序，若仍相同，则**提交日期较早**的模型排序靠前。」

英文手册（[S2]）：

> "The real-time leaderboard is sorted by overall average success rate across all 32 tasks. In the event of a tie, the overall average step score is used as the differentiator. If still tied, earlier submission dates rank higher."

形式化：

```text
rank_key = (avg_success, avg_step_score, -submission_time)
```

这不是「成功率与步骤分加权综合」。上一轮的 `+Δ×q` 杠杆表作废。

### 1.2 单模型规则

中文手册（[S1]）：

> 「所有任务须基于**同一模型**完成，**不得混合使用多个模型**一起进行测试，但对模型类型不作限制（World Model、VLA 均可）。」

英文手册（[S2]）：

> "All tasks must be completed using a single model; mixing multiple models for different tasks is not permitted. There is no restriction on model architecture (World Models, VLAs, and other approaches are all eligible)."

严格读法下的合规边界：

| 组件 | 是否合规 | 理由 |
|---|---|---|
| 同一 checkpoint 的多个头（actor/CTC/step/Q） | 是 | 一个模型 |
| 确定性代码（步骤编译器、脚本原语、时间守卫） | 是 | 不是模型 |
| 外挂 SAM/检测器/独立 reward model/world model | **否（严格读法）** | 第二模型 |
| 每任务 LoRA / 模型合并 / 多模型路由 | **否** | 混合多个模型 |
| 离线用外部工具做数据增强/标注 | 大概率是 | 不在推理路径；仍需在模型卡披露 |

本报告采用**最严格读法**：推理路径只有一个 checkpoint；所有学习组件共享 trunk；外部工具只在离线数据管线出现。

### 1.3 每任务 10 次，5 类泛化各 2 次

中文手册（[S1]）：

> 「每个任务执行 10 次独立运行，每次运行采用不同的泛化设定……10 次运行中包含以下 5 种泛化类型，每种类型各出现 2 次。」

## 2. 形式化：评分表 = 奖励机；排行榜 = 字典序

### 2.1 奖励机（Reward Machine）

把每个任务的官方步骤定义成一台奖励机：

```text
RM = (S, s0, δ, r)
S  = {s0, s1, ..., sk}                 # 官方 score_steps 的顺序
δ  : S × E → S                         # E = 谓词完成/撤销事件
r  : S × E → R                         # r(s_i → s_{i+1}) = w_i（该步权重）
终态 = s_k（所有步骤完成）
```

一次 episode 的累计回报：

```text
G = Σ_i w_i · 1[step i completed] = step_score / 100
success = 1[到达 s_k]
```

排行榜排序：

```text
rank_key = ( E[success], E[G], -submission_time )   # 字典序
```

### 2.2 字典序目标与两个头

```text
主头（success）:  V_succ(s) ≈ P(success | s, instruction)
次头（step）:     V_step(s) = Σ_i w_i · p_i(s),  p_i(s)=P(step i done | s)
```

**为什么主头用 soft-min 而不是加权和：**

在单调完成模型下（step i+1 完成 ⇒ step i 完成），

```text
P(success) = P(所有步骤完成) = min_i p_i
```

soft-min 是 min 的光滑近似：

```text
V_succ = −τ · log Σ_i exp(−p_i / τ),   τ → 0 时 → min_i p_i
```

用 τ=0.1（可学习温度）。这样：

- 前几步很容易、最后一步很难时，soft-min 由最后一步主导 → 与 success 的瓶颈结构一致；
- 加权和会被容易的前几步主导，鼓励「停在 3/4 步」，与字典序排序不一致。

**为什么还需要 V_step：**

- 平局裁决（真实存在：总平均成功率是 1/320 的倍数）；
- 归因诊断（哪一步在丢分）；
- 训练时的稠密梯度（比 0/1 成功更好学）。

### 2.3 潜变量难度模型与评分反演（RID）

设 episode 难度 `d ~ U(0,1)`，步骤 i 成功 iff `d ≤ q_i`（单调阈值；q_i 越大越容易）。则：

```text
p_i = q_i
success p = min_i q_i
step score s = Σ_i w_i q_i
```

定义「其余步骤相对容易度」：

```text
E = (s − p) / (1 − p) = Σ_i w_i · (q_i − p)/(1 − p) ∈ [0, 1]
```

两个极端：

| regime | E | 含义 | 策略 |
|---|---|---|---|
| 平坦/共同因子 | → 0 | 所有步骤一样难；最难一步只比其余略难 | 攻 grasp/perception/语言 grounding 等共同能力 |
| 终端瓶颈 | → 1 − w_term | 只有终端步难，前序几乎全过 | 攻终端放置/插入/闭合 |

**反演步骤：**

1. 从真实 runs 取每任务 `(p, s)`（成功率、步骤分）。
2. 对 2 步任务，闭式解：
   ```text
   q1 + q2 = 2s,  min(q1,q2) = p
   ⇒ 较难步 = p，较易步 = 2s − p
   ⇒ E = (2s − 2p) / (2(1−p)) = (s−p)/(1−p)
   ```
3. 对 n 步任务，在 `q_i ≥ p`、`Σ w_i q_i = s` 约束下，用最大熵/单调先验分配 `q_i`；报告 E 与置信区间。
4. 用 bootstrap over tasks 估计 E 的 CI；若 CI 跨 0.25/0.5 边界，不做强结论。

> 假设说明：d~U(0,1) 是为了把 E 归一化到 [0,1]；若真实难度分布非均匀，E 的绝对值会变，但「平坦 vs 陡峭」的序关系仍可用。报告时必须标注这个假设，不能把 E 当精确的物理量。

**占位数据的演示（只证明方法，不作为结论）：**

| runs 条目 | p | s | E | 若终端唯一瓶颈应有 E |
|---|---:|---:|---:|---:|
| Store Racket | 0.204 | 0.272 | 0.085 | 0.50 |
| Organize Bookshelf | 0.250 | 0.340 | 0.120 | 0.50 |
| Organize Pencil Case | 0.249 | 0.334 | 0.113 | 0.60 |
| Pack Phone | 0.169 | 0.221 | 0.063 | 0.60 |
| Spell robot | 0.340 | 0.464 | 0.188 | 0.75 |
| Hang the Cup | 0.384 | 0.522 | 0.224 | 0.50 |
| **榜首整体** | **0.297** | **0.390** | **0.132** | 0.50–0.75 |

读法：如果这些数字是真的，难度是平坦/共同因子型；终端专项的杠杆被高估。**但它们是占位数据——本轮只用它证明 RID 能区分两种 regime。**

### 2.4 一个必须说清的纠正

我最初用「步骤独立」算了一个 15.2% 的上界，试图证明榜单造假。那个推导是错的：独立假设不成立。正确的 Fréchet 约束下，`P(success) ∈ [max(0, Σp_i−(n−1)), min_i p_i]`；29.7% 与 39.0% 完全相容，只是意味着**步骤失败强正相关**（2 步等权、p=0.297、s=0.39 时，较易步 q2≈0.483，相关系数 ρ≈0.67）。这个更正本身很重要：**失败不是独立丢在每一步，而是有一个共同的 episode 难度因子。** 所以：

- 不能把步骤成功率相乘来估计任务成功率；
- 共同因子（grasp/perception/场景鲁棒性）可能比单步修复更值钱；
- critic 要建模这个潜变量，而不是把每步当独立。

## 3. RC-VLA 架构

### 3.1 总览

```text
┌──────────────────────── Offline（训练与标定）─────────────────────────┐
│ 官方 33k（4 相机 + EE 位姿 + 5 复述 + 官方 score_steps）                 │
│   ├─ RC 编译器：语言→任务→步骤图 + skill token                          │
│   ├─ RTA：CTC 对齐 → 每帧步骤标签/边界（零人工）                        │
│   ├─ Step heads：p_i、V_succ(soft-min)、V_step                          │
│   ├─ FSS：human 剧本 + 反事实 → 负样本/恢复对                        │
│   └─ Q head：demo/扰动/policy chunk → ΔV_succ / ΔV_step                 │
└──────────────────────────────────────────────────────────────────────┘
                                   │
┌──────────────────────── Inference（单一 checkpoint）──────────────────┐
│ language → RC 编译器 → 步骤图 + skill tokens                            │
│ obs(4 相机 + proprio) → 6B trunk                                        │
│        ├─ Actor head → K 个候选 chunk（温度采样 + 脚本原语）            │
│        ├─ RTA head → 当前步骤后验/边界                                  │
│        ├─ Step heads → p_i → V_succ(soft-min), V_step                   │
│        └─ Q head → 每个候选的 ΔV_succ, ΔV_step                          │
│ 字典序重排：max ΔV_succ，再 max ΔV_step                                 │
│ 执行 chunk → 监测 V_succ 停滞/回退 → 恢复（重试/重抓/重放）             │
└──────────────────────────────────────────────────────────────────────┘
```

### 3.2 头与张量

| 头 | 输入 | 输出 | 参数量 |
|---|---|---|---|
| Actor | trunk hidden + language + skill token | action chunk `[H, D_a]`（flow） | 动作专家（全量/LoRA） |
| RTA | 帧级 trunk hidden（2–5fps 池化） | 每帧 `K+1` 类后验（含 blank） | 2 层 Transformer/卷积，~10M |
| Step heads | 当前 trunk hidden + step token | `p_i` for i=1..k；`V_step` | 2 层 MLP，~1M |
| Q head | trunk hidden + chunk embedding | `ΔV_succ`, `ΔV_step` | 2 层 MLP，~2M |

所有头共享 trunk；总新增参数 <50M，仍在「一个 6B checkpoint」内。

### 3.3 损失

```text
L = L_flow + λ1 L_ctc + λ2 L_step + λ3 L_softmin + λ4 L_Q + λ5 L_skill
```

| 项 | 含义 | 起始权重 |
|---|---|---:|
| L_flow | 动作 flow-matching（demo actions） | 1.0 |
| L_ctc | 帧→步骤文本的 CTC | 0.2 |
| L_step | 每步完成 BCE（对齐段 + FSS 负样本） | 0.2 |
| L_softmin | V_succ 与 episode 成功标签的 BCE（含目标互换负样本） | 0.1 |
| L_Q | chunk 价值回归 + margin ranking | 0.1 |
| L_skill | 技能 token 的辅助分类（步骤文本→技能） | 0.05 |

### 3.4 推理循环（伪代码）

```python
def act(obs, language, state):
    task = rubric_compile(language)          # 确定性；160 条复述匹配
    ctx  = encode(obs, task.skill_tokens)    # 一次 trunk forward
    candidates = []
    for k in range(K):
        candidates.append(actor.sample(ctx, temperature=0.7))
    candidates += scripted_primitives(obs, task)   # 确定性，不是模型
    scores = [q_head(ctx, c) for c in candidates]  # ΔV_succ, ΔV_step
    best = lexicographic_argmax(scores)            # success 优先，step 次之
    return best

def monitor(obs, task):
    p = step_heads(ctx)
    v = softmin(p)
    if v <= last_v - eps for W steps:              # 停滞/回退
        trigger_recovery(task, p, obs)
```

## 4. RTA：Rubric-Transcript Alignment（用评分表造免费标签）

### 4.1 为什么是 CTC

数据是「无标注帧序列 + 有序步骤文本」，这正是弱监督动作分割的标准设定：只给 transcript，不给边界。CTC/ECTC 用动态规划边缘化所有合法对齐，不需要帧级标签（[S17][S18]）。相比上一轮的「人工抽检 + 谓词头」，RTA 的优势是：

- 零人工步骤标签；
- 33k 条全部可用；
- 对齐结果同时给出步骤后验、边界、每步时长分布；
- 同一套头可以跨 32 任务共享（transcript 不同，标签空间是技能 token）。

### 4.2 输入与转录稿

```text
帧特征 h_t：trunk 的中间层，池化到 2–5 fps（视频 30fps → 每 6–15 帧一个 token）
转录稿 y：官方 score_steps 的步骤序列，每步映射到 skill token + object token
        例 T27： [place(bowl1), stack(bowl2), stack(bowl3)]
        例 T10： [grasp(strip), grasp(plug), insert(plug)]
blank：CTC 的空白符，吸收停顿/重试/无关帧
```

重复步骤（如三个纸杯）用 object token 区分；若 object 不可识别，用序号 token（cup_1/2/3）。

### 4.3 损失与约束

```text
L_ctc = −log P(y | h_{1:T})                       # 标准 CTC
L_dur = Σ_k (log dur_k − log μ_k)²                # 时长先验（μ_k 来自上一轮 EM）
L_event = BCE(boundary_t, gripper_event_t)        # 弱锚点（权重 0.1）
```

- `L_dur` 防止 CTC 把一步压成 1 帧或吞掉一步；
- `L_event` 只在夹爪开合事件上做弱监督（不是所有边界都有夹爪事件，所以权重小）；
- Viterbi 解码得到每帧步骤标签与边界。

### 4.4 验证（必须先做，否则后面全废）

1. 抽 100 条 episode，人工看边界；记录「边界误差 / episode 时长」。
2. 与夹爪事件比对：grasp/release 应落在某个边界附近（允许 ±10 帧）。
3. 检查每步时长分布：若某步中位时长 <0.3s 或 >总时长 60%，视为对齐失败。
4. **停止条件**：边界误差 >10% episode 时长，或 >20% episode 有明显错位 → 退回「夹爪事件 + 步骤顺序」的规则分段，不强行用 CTC。

### 4.5 伪代码

```python
for episode in dataset:
    h = trunk.features(frames[::stride])          # 2–5 fps
    y = rubric_compile(episode.language).steps    # skill/object tokens
    loss = ctc(h, y) + 0.1*dur_prior(alignment(h,y)) + 0.1*event_bce(h)
    loss.backward()
    labels = viterbi(h, y)                        # 每帧步骤 id + 边界
    save(labels, boundary_conf)
```

## 5. LRC：Lexicographic Rubric Critic（字典序自评头）

### 5.1 训练目标

| 头 | 标签来源 | 损失 |
|---|---|---|
| `p_i`（步骤完成） | RTA 对齐段：步骤 i 边界后=1，前=0；FSS 撤销=0 | BCE |
| `V_succ`（稠密成功值） | 由 step heads 的 soft-min 给出稠密值；另有稀疏校准头：成功 episode 末帧=1，FSS/目标互换=0，中间帧 masked | BCE（校准）+ soft-min |
| `V_step`（步骤分） | 该时刻已完成的步骤权重之和（RTA 对齐给出），不是最终 episode 的步骤分 | MSE |
| `Q(s,chunk)`（chunk 价值） | demo chunk 的 `ΔV_succ/ΔV_step` 伪标签 + 扰动 chunk | 回归 + margin ranking |

**关键细节：`V_succ` 的负样本不能只靠「episode 未结束」。** 那会教模型「时间没到 = 失败」，而不是「状态不对 = 失败」。必须用：

1. **FSS 撤销/破坏**：按官方 human 备注把已完成的对象移走/打开/拔起 → 真实失败状态；
2. **目标互换**：episode A 的观测 + episode B 的指令/目标 → 成功头应为 0；
3. **跨任务负样本**：把 T27 的观测配 T10 的步骤图 → 0。

### 5.2 Chunk-value head 与排序损失

```text
正样本：demo 的 a_{t:t+H}
负样本：a_{t:t+H} + 扰动（空间噪声/时间倒序/夹爪反相/换阶段）
补充：第一轮微调后，用 policy 在 held-out 演示上加噪采样，加入候选集，缩小 train/test 分布差
伪标签：ΔV_succ = V_succ(s_{t+H}) − V_succ(s_t)   # V_succ 用 soft-min 稠密值（0→1），不是稀疏校准头
        ΔV_step = V_step(s_{t+H}) − V_step(s_t)

L_Q = Σ [ (Q_succ(s,a+) − ΔV_succ+)² + (Q_step(s,a+) − ΔV_step+)² ]
      + λ · max(0, m − (Q_succ(s,a+) − Q_succ(s,a−)))
```

推理时：

```text
score(c) = ( Q_succ(s,c), Q_step(s,c) )
best = argmax_lexicographic(score(c) for c in candidates)
```

### 5.3 重排与恢复

- **重排频率**：每个 chunk 边界（2–5Hz），不是每个控制步（30Hz）。
- **候选集**：K 个 actor 采样（温度 0.7）+ 2–4 个脚本原语（移动到当前步骤锚点、开/合夹爪、抬起/放下、微推）。脚本原语是确定性代码，不违反单模型。
- **恢复触发**：
  ```text
  若 V_succ 连续 W=1s 不升（ΔV_succ ≤ 0）：
     若当前步 p_i < 0.5 且夹爪闭合 → 微调/重抓
     若之前完成的步骤 p_j 回退（human 撤销）→ 重置到 j，重放
     若接近终态但 V_succ < 1 → 最终放置/静置/微推
  预算：每 episode ≤2 次恢复，≤20% 的 180s
  ```

### 5.4 为什么不用世界模型 rollout

| 方案 | 额外模型 | 延迟 | 单模型合规 | 证据 |
|---|---|---:|---|---|
| DreamSteer（latent WM + value） | 2 个 | ~13s/次 | 严格读法下不合规 | 23.75→66.25% [S11] |
| 独立 reward model（SARM2/RoboReward） | 1 个 | 低 | 严格读法下不合规 | SARM2 MSE −80%，58→100% [S14] |
| **本方案：Q head（同一 checkpoint）** | **0** | **<500ms（目标）** | **合规** | VGAS/Best-of-Q 支持 chunk 选择 [S12][S13] |

DreamSteer 的增益很大，但 13s/次 + 两个额外模型，在 UniBot 的 180s/单模型约束下不可用。我们用「直接回归 chunk 价值」替代「想象未来再打分」，牺牲一些精度换合规与延迟。

### 5.5 延迟预算

```text
trunk forward（4 相机 480×640，resize 到 320×240，bf16）≈ 60–100ms
actor flow（4 步去噪，batch K=4）≈ 150–250ms
Q head（batch K）≈ 5ms
总计 ≈ 250–400ms（目标 p99 <500ms，2Hz 决策）
```

若超预算：K=2、去噪步数 2、图像 resize 到 256×192、或改成「单 chunk + critic 触发重规划」。

## 6. FSS：Failure Synthesis from Official Scripts（官方剧本的失败合成）

### 6.1 human 备注 = 两次 human 运行（有备注的任务）

手册确认每任务 10 次 = 5 类 × 2；大多数任务有两条 human 备注（`human_1_note`、`human_4_note`；T31/T32 为空）[S1][S16]。高置信推断：**这两条备注就是两次人为干扰的剧本**（编号含义未核实）。这让 FSS 从「自造扰动」升级为「按官方剧本回放」。

典型剧本（来自 `info.json` 的 generalization 字段）：

| 任务 | human_1_note | human_4_note | 破坏→恢复 |
|---|---|---|---|
| T27 StackBowls | 把粉色碗向下移动 | 叠了第二个之后拿下第二个 | 移除 bowl2 → 重放 bowl2 → 继续 bowl3 |
| T19 ZipUp | 把包向左边移动 | 拉上拉链之后拉开 | 拉开 → 重新拉合 |
| T14 PourOutMedicine | 拧开盖子之后拧动回来 | 把瓶子向左移动 | 盖回 → 再拧开 → 倒药 |
| T17 OrganizeStationery | 荧光笔向后 | 笔盒合上之后手动打开 | 打开 → 重新合上 |
| T24 ConveyorSorting | 可乐快到了然后放回传送带起点 | 薯片快到了然后放回传送带起点 | 目标远离 → 重新抓取/放置 |
| T10 PlugCharger | 抓插头前进行移动 | 将插头拔起 | 拔出 → 重新插入 |
| T12 Unlock | 锁向左移动 | 中途把锁拿走 | 重新定位 → 翻环 |

### 6.2 三类负样本

1. **官方剧本回放**：2.5D 场景编辑/重放，按备注做 1-DOF 平移或撤销；30 个有备注任务 × 2 剧本 × 50 ≈ 3,000 对；T31/T32 没有 human 备注，用通用扰动补足。
2. **反事实目标互换**：观测 A + 目标 B → success=0；同任务不同物体位置也算。
3. **截断/阶段错位**：在步骤 i 的中途截断，标签为前 i−1 步完成、第 i 步未完成；只用于 step head，不用于 success head（避免「时间=失败」的捷径）。

### 6.3 恢复对

对每个破坏状态，恢复目标是 demo 中该步骤的原始动作段：

```text
(s_破坏, 目标步骤 j, a_{t_j:t_j+H} from demo) → 正样本   # t_j = demo 中步骤 j 的起始帧
```

训练 actor 的恢复能力 + critic 的「回退检测」。这比上一轮的「可逆信念」简单得多：不需要显式信念变量，只要 step head 的 p_j 回退 + Q head 重排。

## 7. STC：Skill-Token Conditioning（单模型内的 specialization）

### 7.1 技能词表

从 32×5 条步骤文本的动词/宾语归纳 ~12–16 个技能：

```text
grasp, place_into, stack, insert, close, open, zip, pour, fold,
pick_out, hang, flip, lock, store, sort, wipe
```

（可按实际步骤文本合并到 12–16 个；以官方 `score_steps` 的动词为准，不做学习聚类。）

### 7.2 条件化

```text
language 输入 = 原始指令 + "[STEP 2/4] [SKILL: place_into] [OBJ: bowl_2]"
```

- actor：在 cross-attention 的 language token 里加入 skill/step token；
- critic：step head 用 skill token 做条件，Q head 用 (skill, step) 做条件；
- 推理时由 RC 编译器确定性生成，不依赖模型预测（减少误差累积）。

### 7.3 消融

| 配置 | 目的 |
|---|---|
| task token（32 类） | 上界参照（任务 ID 条件化） |
| skill token（~12–16 类） | 主配置：跨任务共享 |
| skill + step index | 主配置 + 阶段信息 |
| none | 下界 |

若 skill token 不优于 task token，砍掉 STC；若优于，说明技能层池化有效。

|---|---|---|---|

## 10. 创新点清单（持续迭代；动机/差异/可行性/资源/步骤/风险/状态）

> 状态：押注=本轮主线；保留=沿用；升级=旧点被改造；降级=保留但非主回路；砍=不做。

### C1 RTA · 评分转录对齐（新增，押注）

- **动机**：33k 条演示没有步骤标签；官方 `score_steps` 给出有序步骤文本。没有密集标签，critic 无法训练；有了它，一份评分表可以同时服务训练、推理、诊断。
- **与现有方案的差异**：CTC/ECTC 是弱监督动作分割的成熟工具，但此前用于烹饪/电影动作；这里把**官方评测 rubric 当 transcript**，用 VLA trunk 当特征，零人工步骤标注，且同一套头跨 32 任务共享。
- **技术可行性**：CTC 是标准动态规划；帧特征来自 trunk；夹爪事件可做弱验证；33k 条可全量。
- **所需资源**：官方 33k（169h）；8×H100 1–2 天特征 + 数小时 CTC；无新标签；接口不变。
- **落地步骤**：解析 `score_steps` → 生成 transcript → 2–5fps 特征 → CTC + 时长先验 → Viterbi → 100 条人工抽检 → 导出标签。
- **风险**：重复步骤/边界模糊/语言不匹配 → 用 object token、夹爪事件、时长先验；停止条件：边界误差 >10%。

### C2 LRC · 字典序自评头 + CVR chunk 重排（新增，押注）

- **动机**：排行榜是 `(success, step_score, -time)` 字典序；单标量 reward 会错位；单模型规则禁止独立 reward model。
- **与现有方案的差异**：soft-min 成功头（直接优化最难一步）+ 加权步骤头（平局/诊断）+ 同一 checkpoint 的 Q head；不是 SARM2/RoboReward 式独立奖励模型，也不是 DreamSteer 式世界模型 rollout。
- **技术可行性**：头共享 trunk；标签来自 RTA + FSS；Q head 用 demo/扰动 chunk 的伪标签；离线可验证。
- **所需资源**：同一 6B checkpoint；新增 <50M 参数；8×H100 1–2 周；推理 1×H100。
- **落地步骤**：step heads → V_succ/V_step → Q head → 离线 top-1 评测 → 延迟压测 → 调试槽定性。
- **风险**：critic hack / 候选多样性低 / 延迟 → 双视角一致性、温度采样 + 脚本原语、K=2 回退；停止条件：top-1 <60% 或 p99 >500ms。

### C3 RID · 评分反演诊断（新增，押注方法论）

- **动机**：在花算力之前，先判断「终端放置专项」还是「共同因子」更值钱；`(success, step score)` 是公开、免费、每任务都有的两个数。
- **与现有方案的差异**：没人把评分表当逆问题；上一轮直接假设终端是闸门，本轮先用单调潜变量模型反演 E，再分配预算。
- **技术可行性**：2 步闭式解；n 步用约束优化/最大熵；bootstrap 出 CI；只需真实 runs。
- **所需资源**：零算力；几小时分析；等真实榜单/运行记录发布。
- **落地步骤**：抓真实 runs → 每任务 (p,s) → 反演 E → 分类 regime → 分配数据/恢复预算 → 复测。
- **风险**：聚合公式未知、步骤相关、样本小 → 用层次模型/CI；占位数据只做方法演示；停止条件：CI 跨 0.25 时不做强结论。

### C4 FSS · 官方剧本失败合成（升级 NRB，保留）

- **动机**：所有演示都成功，critic 需要负样本；官方 human 备注（有备注的任务各两条）很可能就是两次 human 运行的剧本（10=5×2）。
- **与现有方案的差异**：从「自造扰动原语」升级为「官方剧本忠实回放」；同时产恢复对，训练 actor 的撤销恢复。
- **技术可行性**：备注多为 1-DOF 刚体平移/撤销；2.5D 编辑/重放便宜；30×2×50≈3,000 对足够。
- **所需资源**：2.5D 编辑管线；30×2×50≈3,000 对（T31/T32 用通用扰动）；1–2 人周。
- **落地步骤**：备注表 → 场景脚本 → 破坏状态 → 恢复目标 → 训练 → 离线验证。
- **风险**：备注编号含义未核实、sim-to-real 差 → 混入目标互换/跨任务负样本；不把合成当唯一负样本。

### C5 STC · 技能 token 条件化（新增，保留）

- **动机**：单模型 + 32 任务 + 数据不均；不能按任务切模型，只能在 checkpoint 内做条件计算。
- **与现有方案的差异**：不是 task ID 条件化，而是从官方步骤文本归纳的技能 token；跨任务共享，未见任务可组合已知技能。
- **技术可行性**：手工词表 + 嵌入；actor/critic 条件化；消融便宜。
- **所需资源**：无新数据；小改动；1 人周。
- **落地步骤**：词表 → tokenizer → 条件化 → 训练 → 消融（skill vs task vs none）。
- **风险**：词表主观、无增益 → 以官方动词为准；若不如 task token 则砍。

### C6 NAP · 噪声感知评测协议（新增，流程）

- **动机**：10 次/任务的噪声使小增益不可测；相邻名次 <1 SE；早提交有平局优势。
- **与现有方案的差异**：把功效分析写进实验设计；调试槽只做定性/大效应；配对场景；bootstrap CI；提交日历。
- **技术可行性**：纯流程；无算力。
- **所需资源**：无。
- **落地步骤**：功效表 → 决策阈值 → 配对方案 → 提交计划 → 复盘。
- **风险**：规则变化/重提交政策未知 → 以官方邮件确认为准。

### 已砍清单（跨轮）

| 旧点 | 砍的理由 | 保留什么 |
|---|---|---|
| PGL 外挂锚点/SAM | 严格单模型下是第二模型；域差；终端假设不成立 | 可选：同一 checkpoint 的 pointing 头 |
| OPT 放置位姿迁移 | 需容器 6D 位姿估计器（第二模型）；透明/布料失效 | critic 的放置验证 |
| ICR 检索条件化 | 独立编码器/延迟；相对 CVR 的边际增益未证 | 可选：同 backbone 特征离线检索 |
| TCLB/全孪生 | 贵、sim-to-real、对 critic 非必需 | 离线 held-out + 调试槽 |
| L2L 实验室网络 | 外部数据政策未知、组织成本高 | 赛后合作 |
| 每任务 LoRA/模型合并 | 违反单模型规则/精神 | 技能 token |
| World model rollout | 13s/次 + 第二模型 | 直接 Q head |
| FLEET 研究轴 | 部署工程，非研究贡献 | 工程检查单 |
| 「终端放置是普遍闸门」 | 潜变量模型的特例；占位数据 E 偏平坦 | RID 先测量再决定 |

## 14. 开放问题

1. 步骤分的精确聚合：单次运行是「完成步骤权重之和」，还是另有归一化？10 次是算术平均还是取最好？
2. 重提交政策：早提交的平局优势按第一次提交还是最后一次提交计算？是否允许多次提交取最好？
3. 单模型边界：同一 checkpoint 的辅助头是否算一个模型？冻结的视觉编码器/离线工具是否需要在模型卡披露？（本报告按最严格读法。）
4. 外部数据/预训练权重政策：手册后续章节未读到；L2L 默认 OFF。
5. 10 次运行是否使用固定的 10 个场景（可做配对 A/B），还是每次随机？
6. 测试语言是否严格来自 5 条英文复述，还是会有未见复述/中文？
7. 两条 human 备注是否就是两次 human 运行的剧本？编号 human_1/human_4 的含义？
8. 调试通道是否返回分步骤得分（RID 需要）？可用次数/成本？
9. 评测机器人数量/端口并发/延迟上限？
10. 脚本原语（确定性代码）是否被允许作为候选动作？本报告假设允许。
