# 第 44 轮（新循环第 4 轮） · Joint-Space-Cert × MuJoCo-Oracle：把「关节空间可实现性」与「仿真语义可信性」补成证书链的最深两层（四层架构 v9）

> 承接第 43 轮 v20（Persona-Cert × Concurrent-Cert）。v20 自陈最大风险是「共形边际覆盖 + 多用户契约空集」，但它仍压着两个从未被打开的**根假设**：**(H5) 任务空间证书 = 可执行证书**——所有定理都写 ∃a∈A 且默认该 `a` 会被原样执行，却忽略真实机器人是在**关节空间**用带限位/限速/限矩的执行器执行的，任务空间到关节空间的实现映射（冗余消解、奇异、饱和）会**静默改变实际动作**；**(H6) MuJoCo 仿真 = 可信 oracle**——证书在某个"仿真"里通过就被当作可信，却把引擎的**语义版本**（积分器、步长、求解器容差、软接触刚度）默认成稳定不变，且默认 sim-to-real 差异单调可界。本轮灵感词「关节空间控制」「MuJoCo」精确命中这两层：**关节空间控制**迫使我们把证书从「任务空间声明」下沉到「关节可实现 + 力矩可执行」；**MuJoCo** 迫使我们把仿真从"跑一遍看看"升级为"带语义签名、可微、可审计、差异界可证"的**证书 oracle**。二者耦合出全新问题：实现鸿沟与仿真差异在**奇异与接触冲击**处同时被放大，恰好是最危险的地方。

## 0. 直觉与动机

**灵感 1（关节空间控制 → 证书必须过"实现映射"这一关）**：直觉上，"任务空间里安全地伸过去"和"机器人真的能这么动"是两件事。靠近奇异位形时，任务空间一点点位移需要关节速度爆炸（J⁺ 病态）；力矩到顶时，控制器只能饱和，实际加速度被削减，CBF 的 `ḣ+αh≥0` 在力矩层根本不可行；关节限位会把连续指令硬截断，使实际轨迹偏离被认证轨迹。三者都不在任务空间证书里出现，于是证书"通过"只说明**声明动作**安全，不说明**执行动作**安全——我们称这中间的差为**实现鸿沟 Δ_R**。对策是给证书加一条**关节可实现性前提** `Real_J(a)`，并把证书提升到关节空间：C_J = {a : 任务证书 sound ∧ Real_J(a)}。提升只做收缩故 sound 免费，但收缩过度会让证书**可行性崩塌**（大量动作被标 infeasible），这正是 v20「收缩免费、扩张持证」在更底层的一次重演——所以必须同时提供**证书保持的冗余消解**来把可执行集做大。

**灵感 2（MuJoCo → 从"仿真器"升级为"带语义签名的可微 oracle"）**：MuJoCo 给了三样别处没有的东西：**(a) 确定性**——固定语义 σ=(积分器,步长,求解器迭代,软接触 solref/solimp,执行器模型,关节阻尼/摩擦) 后同一初态可复现，证书因此可被第三方逐位审计；**(b) 可微性（MJX）**——`∂h/∂a` 把"证书裕度对动作多敏感"变成可算的量，用来把离散采样外推成连续保证；**(c) 约束求解器残差**——它自己就是一个可信度计：残差大说明这次仿真结论本身不可信。于是定义**oracle 证书** `(h_sim, ∇_a h, residual, σ)`，并规定语义签名一变，旧证书立即失效。但最大的 rigor 陷阱是**差异界的单侧性**：MuJoCo 软接触会"陷进去"，真实刚性接触未必更软，**sim-real 差异在冲击/接触 regime 方向可能翻转**，因此 δ_σ 必须按 regime（自由/接触/冲击）分层标定，绝不能用全局单值。

**灵感 3（耦合 → 两条最深的链条必须联合审计）**：实现鸿沟与仿真差异不是独立的：奇异附近 J⁺ 放大既放大了实现误差，也放大了仿真里的状态估计误差；冲击接触既是 sim-real 差异最大的 regime，又最容易触发力矩饱和。因此不能"先在任务空间认证、再在 MuJoCo 里验一下"就了事，而要把四段拼成**证书链**：任务证书 → 关节可实现 → 力矩/CBF 可行 → oracle 裕度 − δ_σ → 执行。任一段裕度为负，整链降级或停机。这条链把 v20 抽象的"证书 sound"第一次落到**电机与求解器**这一最硬的地面。

**耦合升级**：JSCL（关节空间证书提升器）把任务证书编译成关节可实现 + 力矩可行的证书；MCO（MuJoCo 证书 oracle）提供语义签名、可微裕度与按 regime 的差异界；RGV（实现鸿沟验证器）在线比对"命令动作 vs 实际兑现动作"并在关节层做对抗 fuzz。四层架构由 v20 的「人格 + 并发」升级为 v9 的「+ 关节实现层 + 仿真语义层」，即证书链的两个根。

## 1. 形式化定义（增量：定义 44–49）

**定义 44（实现映射与实现鸿沟）**：关节配置 (q,q̇)∈Q×TQ，限位 q∈[q_lo,q_hi]、|q̇|≤q̇_max、|τ|≤τ_max。**实现映射** R: (a_task,q,q̇) ↦ τ(t) 满足动力学 M(q)q̈+C(q,q̇)q̇+g(q)+Jᵀf_ext=τ 与任务约束。**实际兑现动作** a_exec=FK(q(t))。**实现鸿沟** Δ_R(a)=sup_t d(a(t),a_exec(t))。**可实现谓词** Real_J(a;ε) ⇔ ∃τ∈[−τ_max,τ_max] 使动力学成立、q 不越限、σ_min(J)≥σ_crit 且 Δ_R≤ε。**实现前提命题**：定义 38–43 中任一 sound 结论都隐含 A_exec⊆A_cert；若 a∈A_cert 但 ¬Real_J(a)，则"证书通过"不推出不变式保持（**证书空洞**）。**推论**：关节可实现性不是控制细节，而是所有任务空间安全定理的显式前置条件。

**定义 45（奇异裕度与证书保持的冗余消解）**：奇异裕度 μ_s(q)=σ_min(J(q))；可操作度 w(q)=√det(JJᵀ)。冗余臂的解 q̇=J⁺ẋ+N z，N=I−J⁺J。**零空间证书** C_null={z: q+(J⁺ẋ+Nz)Δt 不越限 ∧ μ_s 保持 ∧ 无自碰撞}。**命题（一阶证书保持）**：因 JN=0，零空间自运动在一阶意义上不改任务输出，故任务证书 margin 不变；但二阶偏差 ‖Δx‖≤½‖∂(JN)/∂q‖·‖z‖²Δt² 必须从任务 margin 中扣减。**定理（联合保持）**：若任务证书在 (q,q̇) 成立且 z∈C_null，则沿该冗余解执行时任务证书与关节可行性同时保持；反之若冗余消解未被认证（z∉C_null），证书在关节层不可保持。

**定义 46（力矩级 CBF 可实现性与可行性损失）**：任务 CBF h(x) 的约束 ḣ=L_f h+L_g h·u≥−αh，经 ẍ=Jq̈+J̇q̇ 与 q̈=M⁻¹(τ−Cq̇−g−Jᵀf) 变为对 τ 的仿射约束。**容许力矩集** T_adm(a)={τ: |τ|≤τ_max ∧ ḣ(τ)+αh≥0 ∧ |q̇+Δt q̈|≤q̇_max}。**关节 CBF 证书** C_J={a: T_adm(a)≠∅}。**可行性损失命题**：任务空间证书只保证"若任务加速度被原样施加则安全"；一旦 τ 饱和使实际 q̈ 被截断，ḣ+αh 可能 <0，而任务证书毫无察觉。**推论**：必须区分「证书 sound」与「证书可实现」，二者之差就是 T_adm=∅ 的动作集合。

**定义 47（MuJoCo 证书 oracle 与语义签名）**：**语义签名** σ=(mjcf 版本, 积分器 η, 步长 h, 求解器迭代/容差, 软接触 solref/solimp, 执行器模型/增益/限幅, 关节阻尼/摩擦)。Oracle O_σ:(x,a)↦(h_sim, ∇_a h, r_sol)，r_sol 为约束求解器残差。**oracle 证书** `Cert_O=(h_sim, ∇_a h, r_sol, σ)`。**可审计性命题**：固定 σ 与初态后 O_σ 确定，故证书可第三方逐位复现；**版本失效命题**：任何 σ 的字段改变（引擎升级、步长变、接触参数变）都使依赖旧 σ 的证书失效，必须重签重校。**可信性判据**：r_sol≤ε_sol 才允许该次 oracle 结论参与守卫；残差超限即视为 oracle 不可信并降级。

**定义 48（sim-to-real 差异界与按 regime 的单侧性）**：差异界 δ_σ(ω)≥0（ω∈{free,contact,impact}）定义为在该 regime 下 m_real ≥ m_sim − δ_σ(ω) 单侧成立。δ_σ 由四源合成：状态估计误差经 Lipschitz 传播、积分截断 O(h^p)、求解器残差、接触刚度失配。**结转判据**：m_sim − δ_σ(ω) ≥ θ 才可用于守卫。**单侧性警告**：MuJoCo 软接触在 contact/impact 下会低估刚性接触的冲击力，差异方向**不保证保守**；因此 δ_σ 必须按 regime 标定，且**未标定 regime 一律取最坏界**（或直接判 oracle 不可用）。**命题（分层必要性）**：δ_free ≪ δ_contact ≪ δ_impact，用单一全局 δ 会在自由段过度保守（可用性崩）或在冲击段低估（静默不 sound）。

**定义 49（联合实现-仿真证书链与链式 sound 性）**：证书链 L = (C_task, Real_J, C_J, h_sim−δ_σ, 执行)。**链式定理**：若四段裕度均非负（任务 margin≥θ、Δ_R≤ε、T_adm≠∅、m_sim−δ_σ≥θ）且各段的保守化只收缩可行域，则联合执行 sound；任一裕度为负则整链降级到"已认证保守子集"或安全停机。**失败分类** F={realization_gap, feasibility_loss, oracle_stale, discrepancy_under}，每类对应一个可审计的降级理由。**推论**：这是 v20 从"证书 sound 口号"到"电机-求解器地面"的完整化；链上最薄的一环决定整体可信度。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-60 JOINT-SPACE CERTIFICATE LIFTER（关节空间证书提升器 JSCL）
1. **实现映射编译**：任务动作 → 关节轨迹，显式处理冗余消解、限位、限速、奇异裕度 μ_s。
2. **力矩级 CBF 可实现性**：把任务 CBF 转成力矩仿射约束，求解 T_adm，输出力矩裕度 m_τ。
3. **证书保持的冗余消解**：在 C_null 内最大化 μ_s / 远离限位，二阶偏差回扣任务 margin。
4. **实现鸿沟度量与单调降级**：计算 Δ_R，超 ε 即判 infeasible 并单调降级，绝不静默放行。

### 2.2 IP-61 MUJOCO CERTIFICATE ORACLE（MuJoCo 证书 oracle MCO）
1. **语义签名与版本绑定**：冻结 σ，证书携带 σ；σ 变即失效重签。
2. **确定性 + 可微 rollout**：MJX 算 ∂h/∂a，把离散采样外推为连续裕度保证。
3. **求解器残差可信度计**：r_sol≤ε_sol 才允许证书参与守卫，残差超限即降级。
4. **按 regime 的差异界**：自由/接触/冲击分层标定 δ_σ(ω)，未标定 regime 取最坏界。

### 2.3 IP-62 REALIZATION-GAP VALIDATOR（实现鸿沟验证器 RGV）
1. **在线鸿沟监视**：比对命令动作 a vs 实际兑现 a_exec，检出奇异逼近、力矩饱和、限位截断。
2. **链式审计**：逐段检查四段裕度，输出失败分类 F 与降级理由。
3. **关节空间对抗 fuzz**：在 MuJoCo 中逼近奇异、注入饱和、制造冲击接触、漂移模型参数。
4. **反例回灌**：把实现/差异反例回灌 SCV 与 CKB，驱动 σ 重校与 δ 更新。

    ← IP-59 ICV(关节层对抗交错) + IP-54 SCV(按 regime 的 sim-real 标定)

## 4. 实验设计（E95–E102 硬门槛，承接 E87–E94）

| 实验 | 指标 | 门槛 |
|---|---|---|
| E95 关节可实现 soundness | 任务证书通过但 ¬Real_J 的静默数；实机越限 | 0；0 |
| E96 奇异/限位/饱和 | 奇异邻域误入；限位越界；饱和未检出 | 0；0；0 |
| E97 MuJoCo oracle 可审计 | 同 σ 复现成功率；σ 变更后旧证书失效检出率 | 100%；100% |
| E98 sim-real 差异界 | 分 regime 的单侧违约率；δ 过保守率 | 0；<20% |
| E99 冗余零空间证书 | 自运动越限；μ_s 保持率；任务二阶偏差 | 0；100%；<5% |
| E100 链式证书可用性 | 非空链证书占比；相对任务单证的可用性损失；链上违例 | ≥85%；<10pp；0 |
| E101 关节层对抗 fuzz | 奇异逼近/饱和注入/冲击下检出率；漏检导致违例 | ≥95%；0 |
| E102 长时程联合闭环 | 100h 不安全事件；oracle 失效次数；链降级率 | 0 起；<10 次；<5% |

回退：E95/E96 不达标 → 所有动作先过在线 JSCL 再执行（牺牲速度）；E97/E98 差异界不可信 → 关闭 oracle 结转，退回解析力矩界 + 刚性接触保守腐蚀 + 降速；E99 零空间证书不可保持 → 禁用冗余自运动，退回唯一解；E100 可用性崩塌 → 允许在自由 regime 使用更紧 δ，但冲击 regime 永久最坏界；任何红线失败 → 全链路熔断回退 v20。

## 5. 本轮最大风险

**一句话**：实现鸿沟与仿真差异在**奇异位形和接触冲击处同时被放大**，而 MuJoCo 软接触使 sim-real 差异的**方向可能翻转**（不是自动保守）——一旦 δ_σ(impact) 被低估或实现映射在奇异附近未被 JSCL 覆盖，「关节可实现 + oracle 结转账」会在最危险瞬间**静默失效**，因此 E96（奇异/饱和）与 E98（分 regime 单侧违约）必须设为红线，并默认回退到「解析力矩硬约束 + 刚性接触最坏腐蚀 + 奇异邻域唯一解」这条不依赖仿真语义的底线。

## 2. 关键算法（伪代码）

### IP-60 JSCL：提升、冗余消解与力矩可行性
```
def joint_realizable(a_task, q, qdot, eps):
    J = jacobian(q)
    if sigma_min(J) < SIGMA_CRIT:            # 奇异邻域直接不可实现
        return False, Failure('singularity')
    xdot = task_velocity(a_task)
    qdot_task = pinv(J) @ xdot
    z = argmax_nullspace_clearance(q, qdot, qdot_task)   # 最大化 μ_s / 远离限位
    qdot_cmd = qdot_task + (I - pinv(J) @ J) @ z
    if violates_limits(q + qdot_cmd * DT):
        return False, Failure('joint_limit')
    qdd_cmd = finite_diff(qdot_cmd, qdot)
    tau = inverse_dynamics(q, qdot, qdd_cmd)             # M qdd + C qdot + g + J^T f
    if max(abs(tau)) > TAU_MAX:
        return False, Failure('torque_saturation')       # 单调降级，绝不静默放行
    if not cbf_torque_feasible(q, qdot, a_task, TAU_MAX):
        return False, Failure('feasibility_loss')        # T_adm = ∅
    drift = 0.5 * norm(dJN_dq(q)) * norm(z)**2 * DT**2   # 二阶偏差回扣
    return True, JointCert(a_task, qdot_cmd, tau, mu=sigma_min(J), drift=drift)

def lift_certificate(C_task, q, qdot):
    C_J = {}
    for a in C_task.admissible:
        ok, info = joint_realizable(a, q, qdot, EPS)
        if ok and info.drift <= C_task.margin(a) - THETA:   # 扣二阶偏差
            C_J[a] = info
    if is_empty(C_J):
        return None, Failure('certificate_vacuous')          # 可用性崩塌 -> 协商
    return C_J, None
```

### IP-61 MCO：语义签名、可微 oracle 与分 regime 差异界
```
def oracle_certificate(x, a, sigma):
    assert sigma.matches(deployed_model())      # 语义签名必须与部署模型一致
    x_next, h_sim, r_sol = mj_step_semantics(x, a, sigma)
    if r_sol > sigma.eps_sol:                    # 求解器残差超限 -> oracle 不可信
        return OracleCert.untrusted(sigma, r_sol)
    grad = mjx_grad_margin(x, a, sigma)          # ∂h/∂a，用于连续外推
    return OracleCert(h_sim, grad, r_sol, sigma)

def discrepancy_bound(sigma, regime):
    base = L_x * sigma.est_err + sigma.solver_tol + integrator_trunc(sigma.h)
    if regime == 'impact':
        return base + impact_contact_bound(sigma.solref, sigma.solimp)
    if regime == 'contact':
        return base + contact_soft_bound(sigma.solref, sigma.solimp)
    if regime == 'free':
        return base
    return WORST_CASE_DELTA                     # 未标定 regime -> 最坏界

def guarded_margin(x, a, sigma, theta):
    cert = oracle_certificate(x, a, sigma)
    if not cert.trusted:
        return None, Failure('oracle_untrusted')
    d = discrepancy_bound(sigma, contact_regime(x, a))
    return cert.h_sim - d, None                  # 结转判据 m_sim - δ_σ >= θ
```

### IP-62 RGV：实现鸿沟监视与链式审计
```
def realization_gap_monitor(a_cmd, a_exec, cert, q, qdot, tau):
    if dist_task(a_cmd, a_exec) > EPS:
        return Degrade('realization_gap')        # 实际兑现偏离命令
    if sigma_min(jacobian(q)) < SIGMA_CRIT:
        return Degrade('singularity_approach')
    if torque_saturated(tau):
        return Degrade('torque_saturation')
    return OK

def chain_audit(C_task, jc, oracle_margin, theta):
    checks = [C_task.margin >= theta,
              jc.realizable,
              jc.T_adm_nonempty,
              oracle_margin is not None and oracle_margin >= theta]
    if all(checks):
        return SOUND
    return Degrade(failure_class(checks))        # 四类失败之一，可审计
```

### IP-51 升级：关节-实现感知的守卫
```
def car_transition_guard_v9(e, x, cert_obj, persona, lease, q, qdot, sigma):
    theta = cert_obj.alpha_e[e] * cert_obj.theta_sim[e]
    m_task = min(cert_lookup_L0(x).m_lo[e],
                 lease.m - lease.lam * (t - lease.tau),
                 persona_cap[e](persona))
    ok, jc = joint_realizable(cert_obj.action[e], q, qdot, EPS)
    m_oracle, fail = guarded_margin(x, cert_obj.action[e], sigma, theta)
    if not ok or fail is not None:
        return False
    return (m_task >= theta and jc.T_adm_nonempty
            and jc.mu >= SIGMA_CRIT and m_oracle >= theta)
```

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| MuJoCo 软接触使 sim-real 差异方向翻转，δ_σ(impact) 低估，冲击时静默不 sound | 高 | E98 红线测分 regime 单侧违约；impact 永久最坏界；未标定 regime 回退；冲击段解析保守腐蚀 |

## 6. 本轮最大风险

**一句话**：实现鸿沟与仿真差异在**奇异位形和接触冲击处同时被放大**，而 MuJoCo 软接触使 sim-real 差异的**方向可能翻转**（不是自动保守）——一旦 δ_σ(impact) 被低估或实现映射在奇异附近未被 JSCL 覆盖，「关节可实现 + oracle 结转账」会在最危险瞬间**静默失效**，因此 E96（奇异/饱和）与 E98（分 regime 单侧违约）必须设为红线，并默认回退到「解析力矩硬约束 + 刚性接触最坏腐蚀 + 奇异邻域唯一解」这条不依赖仿真语义的底线。
