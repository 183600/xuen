# 第 51 轮（承接第 50 轮 v14；新灵感循环第 1 轮；本轮灵感：需求洞察 × 可解释性） · NeedExplain-Forge：需求缺口证书 × 忠实解释证书 × 知情同意门（九层架构 v15）

> 承接第 50 轮 v14 CoStride-Distill。v14 把安全论证推进到"共创契约 × 双足可行证书 × 证书引导蒸馏"，并用 propose–dispose 把蒸馏从精度风险改造成可用性风险。但它仍隐含两个新假设：**H11：陈述需求 = 真实需求**——目标/条款以文本或语音给出的那一刻就被当作忠实编码，正确执行 r 就等于服务了潜在需求 n；**H12：用户可以是黑箱**——只要执行正确、签名齐全，用户是否"理解"自己签了什么、系统是否"说得清"为什么放行/拒绝，都不进入安全与授权论证。两个灵感词精确命中：**需求洞察**打破 H11（陈述需求是潜在需求在特定上下文里的有损投影，字面正确可以是"安全地做错事"；系统必须显式建模需求缺口、用有限次数的高价值澄清来消解，而不是无脑执行或无限追问）；**可解释性**打破 H12（"知情同意"要求用户理解决策后果，解释必须是**证书**而非事后散文——可被精确求值器反事实验证、可被证伪，且不可由被蒸馏的 student 自证；否则共创就退化成"签字剧场"，把未经理解的授权洗进证书栈）。两者耦合出一个新的认知层：**需求推断只能"提议"重解释，不能自行扩张认证动作集（权威中性）**；**解释生成可以蒸馏（搜索），解释验证绝不可蒸馏（评估）**；**无法给出忠实后果解释的条款一律拒签（对知情同意 fail-closed）**。

## 0. 直觉与动机

**灵感 1（需求洞察 → 从"执行指令"到"消解需求缺口"）**
直觉：用户说"把窗户打开"，可能是热、可能是要新鲜空气、可能是要看清外面、也可能是要逃离。字面执行 r 在每一种 n 下都"成功"，但只有一种 n 被真正满足。传统 HRI 把 r 当目标、把安全当唯一硬约束；于是最危险的失败不是碰撞，而是**安全地做错事**——系统完美地完成了不该做的事，或把"快一点"当成"可以牺牲稳定性"。需求洞察的正确形式化不是读心，而是：维护潜在需求后验 `b_n`，定义"现在就拍板"的贝叶斯后悔 `A_need`，当 `A_need` 高且"错误代价 × 不可逆性"高于打扰成本时，发起**被认证的澄清动作**（问、给选项、预览、演示）；否则回退到**字面默认**并把推断显式说出来。关键纪律：**需求推断只提供重排序/重路由，任何因需求而改变的动作仍必须过原证书栈与共创能力格**——它不能成为绕过安全的侧门。

**灵感 2（可解释性 → 解释是一张可证伪的证书，不是一段好听的话）**
直觉：大多数 XAI 产出的是"看起来合理"的事后叙述，而事后叙述可以被任意编造以迎合听众——这正是"解释剧场"。在证书栈里我们已经有精确的求值轨迹 τ；解释应当是从 τ 里**抽取**出来的因果见证，而不是让模型再讲一个故事。我们说解释 E 忠实，当且仅当：(i) 引用的每一项都真的出现在 τ 里；(ii) 把这些项固定为 τ 中的值、用精确求值器重算，确实复现该决策（充分性）；(iii) 去掉任一项充分性即破坏（非冗余）；(iv) 每条"若不是 f=f' 就会改判"的反事实断言都被精确重算确认。这样的解释天然可证伪：EXF 周期抽样、重放反事实、检查"重大遗漏"（某个但-for 必要且会改变用户行为的项没被披露）。**解释证书 CoE 只能由精确守卫签发，student 只能提议解释候选**——这是 v14"蒸馏只许近似搜索"红线的第二块拼图。

**灵感 3（可解释性 × 共创 → 知情同意必须可证书化）**
直觉：v14 的共创契约靠双签署与能力格合法化，却没有回答"用户是否理解自己签了什么"。签一个"允许在厨房走快一档"之前，用户有权知道它会怎样改变认证包络（最大速度、捕获域、MRC 概率、各 α 项）。我们把"知情"操作化：条款 κ_c 必须附带**后果解释** E_κ，精确刻画 `Δ`（认证集/最大速度/捕获域/MRC 概率/风险项的证书化上界）；同意有效当且仅当 E_κ 忠实 ∧ 用户通过理解检查 ∧ 双签署 ∧ 版本匹配。**若无法在预算内忠实刻画后果，则拒签该条款——对知情同意 fail-closed，而不是"先签了再说"**。这把"知情同意"从道德修辞变成一条可执行的守卫条件。

**灵感 4（需求洞察 × 安全 → 权威中性原则）**
直觉：如果需求推断能直接放宽速度或扩大工作域，那么一次错误推断就等于一次越权——"善意读心"会变成"安全侧门"。因此设**权威中性（authority-neutral）**：需求推断与澄清的产物只能改变"在已认证动作集内选哪个/是否先澄清/是否请求授权"，不能改变动作集本身；任何需要扩张包络的重解释必须回到 UCC（能力格 + 不可委托 + 双签署 + 后果解释）。于是需求错误只会降低**任务效用**（`α_need`），不会进入**物理安全**上界；这与 v14"student 误差只损失可用性"构成对偶。

**灵感 5（需求洞察 × 可解释性 → 用户是需求模型的共同校正者）**
直觉：系统推断的潜在需求本身也必须可解释、可纠正——"我猜你想要 X，因为 Y，是否如此？" 用户对需求推断的纠正，既是澄清，也是需求模型的共同作者信号（接入记忆与兑现率）。这把 v14 的"共创契约"扩展到"共创**需求**"：契约共同作者之上，再加一层需求模型共同校正者。风险对称：纠正也可能被滥用（诱导系统放宽），所以纠正同样是证据而非真值，且受权威中性约束。

**耦合升级**：v14 八层之上，在 L2 与 L2.5 之间插入 **L2.2 需求洞察与澄清层（NID/NCC）**，在 L4 守卫处新增 **CoE 签发**，在 L6 新增 **EXF 解释证伪**，并把 **ICE 知情同意门**并入 L2.5。九层 v15：根信任+用户能力格 + L1 几何感知 + L2 任务分解/上下文/记忆/语音 + **L2.2 需求洞察与澄清（NID/NCC）** + L2.5 交互安全与共创契约（IPC+UCC+ICE）+ L3 关节证书/抽象/交互感知决策 + L3.5 动力可行（HVC/CRM）+ L4 CAR/Shield/CBG+/KDX 守卫（+CoE 签发）+ L5 DCL/真机评测（+需求/解释日志）+ L6 原型证伪/XFER/LFF（+EXF）。JCPS 输出升级为 `(v_t^*, a_t^*, m_t^*, q_t^*, ι_t, κ_t, ν_t, ξ_t)`（ν=需求假设，ξ=认知动作：澄清/解释/让渡/执行）。

## 1. 形式化定义（增量：定义 87–93）

**定义 87（潜在需求模型与需求缺口）**
需求空间 𝒩、陈述空间 ℛ、上下文 𝒞。表达似然 `P(r|n,c,u)` 描述"需求 n 在用户 u、上下文 c 下被说成 r"的概率；需求后验
`b_n(n) ∝ P(r|n,c,u)·b_n^0(n)·(1+ω_u·h_u(n))`，
其中 `h_u(n)` 为用户历史/共创/澄清记录。给定认证动作集 `A_cert`（已由 L3–L4 保证安全），定义承诺后悔
`A_need(b_n) = E_{n~b_n}[ max_{a∈A_cert} U(a,n) ] − max_{a∈A_cert} E_{n~b_n}[U(a,n)]`
（完美信息价值的上界，即"现在拍板"的期望损失）。当 `A_need > ε_need` 时称存在**需求缺口**。注意 `A_cert` 是外生给定的：需求模型不能扩张它。

**定义 88（澄清动作、信息价值与扰动预算）**
澄清动作集 `𝒬={ask, options, preview, demonstrate, defer}`；每个 `q∈𝒬` 本身必须安全（过 `G_exact`）并有不打扰成本 `c_q`（时间/隐私/打断）。其信息价值
`VoI(q; b_n) = A_need(b_n) − E_{z~P(z|q)}[ A_need(b_n^{q,z}) ] − c_q`。
澄清策略：当且仅当 `VoI(q)>0 ∧ A_need>ε_need ∧ 本周期打断数 < B_q ∧ 用户未设"字面优先"` 时发起 q；否则执行**字面默认**并显式返回推断（"你要求 r；我理解为 n；当前按 r 执行"）。**让渡单调性**：用户明示"就按字面办"时提高字面权重、降低追问；用户明示"你决定"时提高推断权重。

**定义 89（需求-执行一致性证书）**
对动作 `a` 与需求后验 `b_n`，定义
`R_need(a,b_n) = E_{n~b_n}[U(a,n)] − max_{a'∈A_cert} E_{n~b_n}[U(a',n)] ≤ 0`。
`a` 是 `(ε,1−α_need)`-**需求一致**的，若 `R_need(a,b_n) ≥ −ε` 且该界在 `b_n` 的 `1−α_need` 可信集上成立。字面默认 `a_lit` 必须要么满足该证书，要么把缺口显式上交（触发澄清或共创授权），不得静默选择。需求一致性只在 `A_cert` 上评估——**需求洞察权威中性**。

**定义 90（忠实解释与解释证书 CoE）**
决策 `d` 的精确轨迹 `τ = {(f_j,v_j,θ_j)}`（证书项/阈值/求值结果）。解释 `E = {(f_j, role_j, cf_j)}` 忠实当且仅当：
(F1) **出处**：每个被引 `f_j` 及其值都出现在 τ 中；
(F2) **充分**：把被引项固定为 τ 中的值、用精确求值器重算，复现 `d`；
(F3) **非冗余**：去掉任一被引项后 F2 失败（或达到最小基数预算）；
(F4) **反事实有效**：每条 `cf_j`（"若 f_j 取 v_j' 则 d 翻转"）都被精确重算确认。
**解释证书** `CoE=(d,E,h(τ),{验证见证},Sig_guard)`，`h(τ)` 绑定轨迹哈希；**仅 `G_exact` 可签发**。student 产出的只是解释候选；未经精确验证的叙述只能标注为"建议理由"，永不得作为安全/拒绝/同意理由展示。**解释可证伪原则**：CoE 是可被 EXF 检验的对象，不是散文。

**定义 91（后果解释与知情同意门 ICE）**
对共创条款 `κ_c`，其后果函数
`Δ_κ = (ΔA_cert, Δv_max, Δcapture-region, ΔP(MRC), Δα_terms)`
必须由精确求值器给出**证书化区间**。后果解释 `E_κ` 忠实当且仅当每条区间都被精确验证。同意有效当且仅当：`E_κ` 忠实 ∧ 用户通过理解检查 `comp(E_κ,u) ≥ θ_c`（复述/选择/演示）∧ 双签署 ∧ `ver` 匹配。同意无效的条款按**未签署**处理、不计入 `ω_u`；若 `Δ_κ` 在预算内无法被忠实刻画，则**拒签**（对知情同意 fail-closed），绝不"先签后验"。

**定义 92（解释证伪 EXF 与重大遗漏）**
解释台账 `L_E` 存 CoE 及其**遗漏集**（τ 中未引用的项）。EXF 周期抽样 `(d,E)`，执行：(a) 重验 F2/F4；(b) **重大遗漏检验**——若某未引项是 `d` 的但-for 必要项，且披露它会改变用户的可行动空间/决定，则记为重大遗漏违规。违规则**撤回**该 CoE（标记失效）、入 DCL、重训解释候选器；撤回的 CoE 不再能充当同意/拒绝理由，直到重新签发。EXF 与 v14 的 PFV/LFF 同构：**解释也要被证伪，而不是被相信**。

**定义 93（十源归因与认知失效项）**
`DDA` 由八源扩为**十源**：感知/关节/边界/意图/接触/传输/动力/蒸馏/**需求（need）**/**同意（consent·解释）**。`α_need` = `(ε,α_need)` 需求一致性被违反的概率；`α_consent` = 同意实际无效（后果解释不忠实或理解未达标）的概率；`α_expl` = 展示的 CoE 不忠实的概率。**`α_need` 只进任务效用界、不进物理安全界**（权威中性）；`α_consent` 仅经共创条款进入安全界（无效同意按未签署处理）；`α_expl` 通过"是否可作为理由展示"影响沟通与信任，而不直接放行动作。

## 2. 新增产出与既有 IP 升级

**IP-91 NID（Need Insight Dialogue）**：潜在需求后验 + `A_need` 决策后悔 + VoI 门控的认证澄清 + 字面默认/让渡单调。
**IP-92 NCC（Need-Consistency Certificate）**：`(ε,α_need)` 需求一致性证书；只在 `A_cert` 上评估，权威中性。
**IP-93 CoE（Certificate of Explanation）**：从精确轨迹抽取的忠实/最小/反事实有效解释；仅守卫签发，student 只提议。
**IP-94 EXF（Explanation Falsification）**：解释台账 + 反事实重放 + 重大遗漏检测 + 撤回机制。
**IP-95 ICE（Informed Consent Explanation gate）**：后果解释 `Δ_κ` + 理解检查；不可解释即拒签。

**既有 IP 升级**
IP-86 UCC：条款签署前必须过 ICE；需求模型的用户纠正作为共同校正证据入账；能力格不变。
IP-80 SIG：意图后验增加需求证据通道（`b'(θ)` 由已签承诺与需求后验共同锐化）；σ 硬下界不动，需求不确定并入 σ。
IP-79 SIC：认知状态扩为 `z=(x_r,x_h,x_e,κ,ν)`，ν 为需求假设；∀人动作∃机器序列仍按认证集评估。
IP-85 MRC / IP-88 CRM：MRC 触发必须先发 CoE（"为什么进入 MRC"）并检验同意是否覆盖该情况。
IP-89 KDX：student 新增解释候选头；**解释候选必须过精确验证才成为 CoE**；红线扩为"搜索可近似，求值与解释验证不可近似"。
IP-90 LFF：证伪预算同时服务 EXF（解释薄弱区域优先重放）。
IP-77 DDA：八源 → 十源（+需求、+同意/解释）。
IP-61 DCL：新增需求错配、解释不忠实、重大遗漏、无效同意、过度追问/澄清疲劳五类样本。
IP-62 CCA：新增需求操纵（谎报需求以扩权）、解释操纵（用动听说辞骗同意）、同意疲劳、解释隐私泄露红队。
IP-51 CAR：守卫条件加"需授权动作的 CoE 已签发 ∧ 同意哈希匹配"。
IP-45 总线：新增 need-posterior / clarification-request / explanation-certificate / consent-version 话题。
IP-66/67/68：语音同时是澄清与解释通道；记忆存需求模型史与解释台账；SAB 队列处理澄清/解释请求。
IP-75 ASC：抽象决策纳入需求模糊度（`A_need` 高时取保守/字面或先澄清）。
IP-74 HTD-Cert：分解节点可为认知节点（澄清/解释子任务）；边蕴含携带需求一致性证书。
IP-72 RRP：e-process 纳入需求/同意证据；跨层传输仍带 δ。
IP-76 CCL：升级为 `CCL+++`（定义 93），追加需求推断、CoE 哈希、同意校验、解释撤回事件，仍只追加。
IP-73 JCPS：联合输出增 `ν_t,ξ_t`，认知动作与物理动作同调度但受各自证书约束。

## 3. 算法骨架

每个宏周期：
1. 读目标、`C_t`、租约、`CCL+++`、契约版本 `h(κ_c)`；任一失效 → fail-closed。
2. HTD-Cert 展开/复用 DAG，前沿标注交互子任务 ι、步态子任务 κ、**认知子任务（澄清/解释）ξ**。
3. **NID**：由陈述 r、上下文、记忆、澄清历史更新 `b_n`；计算 `A_need`；若超阈值且 `VoI>0` 且未超打断预算 → 发起认证澄清 `ξ=ask/options/preview`，等待或按预算超时回落；否则取字面默认并显式回传推断。
4. **需求-执行**：用 `NCC` 在 `A_cert` 上选动作；若字面默认无法取得需求一致性证书 → 上交（澄清或请求共创授权），不得静默。
5. **共创**：新条款过能力格+不可委托+双签署；**ICE 计算 `Δ_κ`、生成后果解释、执行理解检查**；不可忠实解释 → 拒签；通过则更新契约并异步重解/重蒸馏/再认证，旧 student 即刻失效。
6. **KDX 提议-处置**：student 提议 `(u_r,a,m,q,ι,κ,ν,ξ)`；`G_exact` 精确求值 B/B_v/PFL/Inv/共识/版本/租约；通过才执行。需要解释时，student 提解释候选，**守卫精确验证后签发 CoE**。
7. **HVC/CRM**：维持可行内近似与时间边界；接近边界触发捕获准备；MRC 触发签发 CoE。
8. 执行前后 CBG+ 复核边界∧屏障∧可行∧PFL∧共识∧版本∧（如适用）同意哈希；通过才追加 `CCL+++`。
9. **EXF/PFV/LFF 并行**：EXF 抽样重放解释与反事实、检测重大遗漏、必要时撤回 CoE；PFV+LFF 证伪证书；新反例/解释失败回灌 DCL/CCA 并共蒸馏 student、解释候选器与 LFF。
10. 所有路径（抽象、协议、共创、需求、解释、蒸馏）不可行 → 技能合成 / 人工接管 / 保护姿态 / fail-closed，绝不绕过 L3.5、精确守卫与 ICE。

## 4. 本轮最大风险

### IP-91 NID（需求洞察与澄清）
```
def need_insight(r, ctx, user, b_n_prior, dcl, interruption_budget):
    b_n = normalize(b_n_prior * P(r | n, ctx, user)
                    * (1 + omega_u * dcl.need_history(user)))
    A = bayes_regret(b_n, A_cert)              # 现在拍板的期望后悔
    if A <= EPS_NEED or user.deference == 'literal_max':
        return ('act_literal', b_n, A)         # 字面默认，显式回传推断
    best_q, best_voi = None, 0.0
    for q in Q_CERTIFIED:                      # ask/options/preview/demonstrate
        if not guard.exact_check(q.action, contract_version(ctx)):
            continue                           # 澄清动作本身必须安全
        if interruption_budget.remaining(q) <= 0:
            continue
        voi = A - expected_regret_after(q, b_n) - q.cost
        if voi > best_voi:
            best_q, best_voi = q, voi
    if best_q is not None:
        return ('clarify', best_q, b_n, best_voi)
    return ('act_literal', b_n, A)             # 不打扰优先，缺口显式上交
```

### IP-92 NCC（需求一致性证书）
```
def need_consistent(a, b_n, A_cert, alpha_need):
    R = expected_utility(a, b_n) \
        - max(expected_utility(a2, b_n) for a2 in A_cert)
    # 结论必须对 1-alpha_need 需求可信集一致成立
    return all(R >= -EPS_NEED for b in credible_set(b_n, 1 - alpha_need))

def literal_default(r, b_n, A_cert):
    a_lit = argmax([a for a in A_cert if satisfies(r, a)],
                   key=lambda a: expected_utility(a, b_n))
    if need_consistent(a_lit, b_n, A_cert, ALPHA_NEED):
        return ('ok', a_lit)
    return ('escalate', 'clarify_or_co_create')   # 绝不静默选错
    # 注意：A_cert 由 L3-L4 外生给定，需求模型无权扩张 -> 权威中性
```

### IP-93 CoE（守卫签发忠实解释）
```
def issue_coe(decision, trace, candidate_expl, guard):
    E = [t for t in candidate_expl.terms if t in trace]     # F1 出处
    if not recompute_matches(decision, E, trace):           # F2 充分
        return ('reject', 'insufficient')
    for t in list(E):                                       # F3 非冗余
        if recompute_matches(decision, [x for x in E if x != t], trace):
            E.remove(t)
    for cf in [c for t in E for c in t.counterfactuals]:    # F4 反事实
        if not exact_recompute_flips(decision, cf, trace):
            return ('reject', 'bad_counterfactual')
    return CoE(decision, E, hash(trace), witnesses, sign=guard.sig)
    # student 只能 propose_explanation(...)；未经此函数校验的叙述
    # 仅可标注为"建议理由"，绝不作为安全/拒绝/同意理由展示
```

### IP-95 ICE（知情同意门）
```
def informed_consent(clause, user, guard, budget):
    delta = guard.certify_consequence(clause, budget)   # 精确、有界
    if delta is None:
        return ('reject', 'consequence_not_certifiable')  # fail-closed
    E_k = guard.explain_consequence(delta)                # CoE 式后果解释
    if not guard.verify_consequence(E_k, delta):
        return ('reject', 'unfaithful_consequence')
    if comprehension_check(user, E_k) < THETA_C:
        return ('reject', 'not_informed')                 # 签字但未理解
    return Contract(scope, clause, user.sig, sign_template(clause),
                    E_k=E_k, ver=next_ver(contracts))
    # 无效同意按"未签署"处理；不计入 omega_u；绝不先签后验
```

### IP-94 EXF（解释证伪）
```
def falsify_explanations(ledger, budget, scenario_sampler):
    for (d, E, trace, omissions) in ledger.sample(budget):
        if not recompute_matches(d, E, trace) or not all_cf_valid(E, trace):
            ledger.retract(E); dcl.record('unfaithful_explanation', E)
            continue
        for f in omissions:
            if is_butfor(f, d) and disclosure_changes_user_action(f):
                ledger.retract(E)                 # 重大遗漏
                dcl.record('material_omission', E, f)
                break
        else:
            ledger.confirm(E)
    return ledger.coverage()
    # 撤回的 CoE 不再充当同意/拒绝理由，直到重新签发
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| NID | O(|𝒩|·|𝒬|·c_U) 后验/后悔 | O(|𝒩|+记忆) | 澄清动作须过 G_exact；不打扰优先；推断显式回传 |
| NCC | O(|A_cert|·c_U) 后悔求值 | O(1) | 只在 A_cert 上评估；权威中性；可信集一致 |
| CoE | O(|E|·c_eval + |cf|·c_eval) | O(|τ|) | F1–F4 全过才签发；仅守卫签名 |
| ICE | O(c_certify + c_comp) | O(|Δ_κ|) | 后果不可证书化即拒签；无效同意按未签署 |
| EXF | O(B_E·c_eval) 抽样重放 | O(|L_E|) | 无放行权；失败只撤回解释、入账、重训 |
| G_exact | Σ cost(精确求值) ≤ τ_g | O(1) | 看门狗超预算强制安全慢模式（承袭 v14 A11） |
| 认知层合计 | 与主循环并行/异步，超时回退字面默认 | — | 认知延迟只影响效用/沟通，不影响放行标准 |

**正确性定理（Epistemic-Safety Compositional Soundness）**
假设：(A1)–(A12) 承袭 v14（契约 sound、CBG 边界蕴含、租约、初始证书、CCL 只追加、意图支撑覆盖、δ 膨胀不被低估、MRC/CRM 可达、`C_cert` 内近似、捕获可恢复、`G_exact` cost-certified、共创过格且版本钉住）；新增
**(A13) 权威中性**：`A_cert` 仅由 L3–L4 决定，`b_n`、澄清与需求推断不能改变它，且需求一致性界在 `b_n` 的 `1−α_need` 可信集上成立；
**(A14) CoE 签发**：任何作为安全/拒绝/同意理由展示的解释都是守卫签发的 CoE，其 F1–F4 成立；student 解释未经精确验证不得充当理由；
**(A15) ICE**：任何被接受的条款都有忠实的后果解释且用户通过理解检查，否则按未签署处理；后果在预算内不可证书化即拒签。则
- **物理安全**（α_need、α_expl 不进入）：
`P(∀t≤T: z(t)∈Z_safe) ≥ 1 − Σ_i α_i − Σ_i ε_hand,i − α_lease − α_intent − α_user − α_viable − α_cap − α_consent − Σ_ℓ δ_{ℓ→d}`；
- **任务效用**：`P(需求被满足) ≥ 1 − α_need − α_intent`；
- **解释可信**：`P(展示的 CoE 忠实) ≥ 1 − α_expl`；
- **授权合法**：任一被接受条款 ⇒ 有效知情同意，概率 ≥ `1 − α_consent`。

**不对称性（与 v14 对偶）**：v14 的蒸馏误差只提高回退率 `r_fb`，不进入安全上界；v15 的需求/解释误差只降低任务效用或沟通质量——需求推断不能扩张 `A_cert`（A13），解释生成可蒸馏但解释**验证**与 CoE **签发**只在 `G_exact`（A14），同意在后果不可解释时 fail-closed（A15）。因此"认知不确定性损失的是有用性与信任质量，不是物理 soundness"。这仍是**条件保证**：`b_n` 对真实需求的后验校准、`Δ_κ` 的可证书化程度、理解检查的区分度是新的信任锚，由 DCL/CCA/EXF 的持续证伪与用户研究负责，不在定理覆盖范围内。

## 6. 本轮最大风险

**一句话**：新增的认知层把安全与授权挂在两个新的信任锚上——**需求后验是否真的跟踪潜在需求**、**后果解释能否被精确证书化**；一旦需求推断被当成扩权依据（破坏权威中性），或解释退化为不可证伪的事后叙事、同意变成没理解的"签字剧场"，CoE 就会从"信任凭证"变成"信任洗白装置"，因此需求推断必须权威中性+字面默认、CoE 必须守卫签发+精确反事实验证+EXF 持续证伪、同意必须在后果不可解释时 fail-closed。
