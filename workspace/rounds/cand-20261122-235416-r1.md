# 第 1 轮（灵感驱动研究循环·新灵感二元组第 1 轮；本轮灵感：「手势识别」×「实时控制」）

> **基线**：MetricVoiceGauge-NCD-HUTDH-v21（第 3 轮语义-规范层 SDC/CAC/DCL/GIC/HPC+/CFC+，上承 v20 联邦感知证书与 v19/v17 各模块）。
> 本轮纪律：**手势是带时间戳的延迟观测，控制是带硬截止的连续过程；安全必须同时对手势的"晚"与"无"成立**。不推倒 v21：SDC/CAC/DCL/GIC/HPC+/CFC+ 全部保留。本轮只做一件事：**把 GIC 从"单帧意图分类器"升级为"时间语义上的实时意图控制层 RT-GICL"，用延迟即不确定、安全意图锁存、实时预算分离三条原则，让手势能驱动 50Hz+ 控制环而不破坏 v21 的安全继承**。

## 0. 直觉与动机

**灵感 1（手势识别 → 延迟、稀疏、抖动的时间证据）**
直觉：v21 的 GIC 把一帧手势分类成意图 `î` 和置信 `q`，然后立刻改写规范状态。但真实手势是**一段带 onset/offset 的运动轨迹**：识别器在 100–300ms 后才给出标签，标签还会中途翻转（"手抬起→停住→收回"）。把"识别完成的时刻"当成"意图成立的时刻"，等于**假装延迟不存在**——人在 `t₀` 做出 STOP，机器人在 `t₀+L` 才"看见"，而这 L 毫秒里它已沿原速度前进。核心创新：**延迟感知意图时域 (Latency-Aware Intent Horizon, LAIH)**——每条手势观测记成 `(onset, recog, Γ)`，在 `[onset, recog]` 这段"在途窗口"内，控制环必须对**所有与在途观测相容的意图之并**保持安全；延迟不是噪声，而是**显式的意图不确定集 I(t)**。关键反直觉点：**手势迟到本身不是安全问题，忽略它才是**——因为"STOP 可能仍在途中"本身就是一条可规划的安全约束。

**灵感 2（实时控制 → 硬截止、WCET、连续时间安全）**
直觉：控制环是 50Hz（20ms）甚至更高，而手势感知是软实时的（帧率不稳、推理抖动）。把慢感知塞进快控制，要么违反截止时间（抖动），要么为等手势牺牲活性。核心创新：**实时预算分离 + 混合关键性调度 (Mixed-Criticality Gesture Scheduler, MCGS)**：硬实时安全路径（反射式减速/停）**不依赖手势识别**、有 WCET 上界；手势识别跑在软实时感知路径，只能**追加**约束。再用 **控制屏障函数意图调节器 (CBF Intent Governor, CBF-IG)** 把锁存意图翻译成时变 CBF 约束——**两次手势更新之间的连续时间安全由 CBF 保证，与控制环是否收到新手势无关**。关键反直觉点：**实时性不是"把手势识别做得更快"，而是"让安全不依赖识别速度"**。

**灵感 3（两者交汇 → 安全意图锁存与非对称时间语义）**
直觉：既然手势会迟到，"撤销许可"（STOP）与"授予许可"（GO）在时间上就该被区别对待。把 STOP 延迟应用，危险；把 GO 提前应用，同样危险。核心创新：**安全正意图锁存律 (Safety-Positive Latching)**——STOP/让位/减速这类**安全正**意图一旦识别就**回溯到 onset 生效并锁存**（在途窗口内已发生的运动会被判为违规并触发补偿），直到高门槛证据 + TTL 才解除；GO/接近/加速这类**安全负**意图**只从识别时刻向前生效、不回溯、按 TTL 过期**。关键反直觉点：**时间语义的不对称使延迟只会让系统更安全、绝不会更危险**——晚到的 STOP 仍回溯生效，晚到的 GO 只是少赚一点活性。

**三者如何统一**
统一为 **实时手势意图控制层 RT-GICL**，包裹并复用 v21 的 GIC。共享状态扩展为 `ζ_rt = ζ_sem ∪ (O_inflight, λ, I(t), sched, cbf_state, tsc)`。准入门升级为 **HPC++ = (HPC, CC, AbsCert, TSC)**：TSC 记录手势的 onset/recog/latch 区间，使"停止是何时、因何而生效"可机械复核。安全继承方向不变：手势只能**加约束**，实时调度只能**降级到锁存态**，故 `Exec_v22 ⊆ Exec_v21`。

## 1. 研究问题（轮次升级版）

- **Q1（延迟 → 不确定集的可靠转换）**：如何由延迟分布 `L` 与 onset/offset 检测误差，构造覆盖 `[t-L_max, t]` 的意图不确定集 `I(t)`，使真实意图以 ≥1-ε 落入其中？在途观测的并集如何避免"永远保守"（活性坍缩）——何时可以安全地**排除**某个在途 SP 意图？

- **Q2（连续时间安全与硬截止）**：如何把锁存意图编译为 CBF 约束，使两次手势更新之间的**任意**控制输入都保持安全集前向不变？STOP 的 `τ_stop` 硬截止如何与 CBF 可行性、v21 DCL 的 SafeStop 升级路径衔接而不重复触发？

- **Q3（混合关键性调度与降级）**：手势无关的硬实时反射路径与软实时手势路径如何分配 WCET 预算与优先级？手势管线错过截止时间时，"降级到锁存态 + 反射减速"如何保证本身安全、且不产生模式抖振？

- **Q4（非对称时间语义与审计）**：安全正意图的"回溯生效"如何界定回溯窗口与补偿动作？安全负意图的 TTL 与 v21 的 `TTL_intent`、v17 APS 新鲜度阶梯如何统一？TSC 如何在时钟同步误差有界的前提下做到可审计复放？

## 2. 设计原则（在 P34–P36 基础上新增 P37–P39）

**P37 延迟即不确定律（Latency-as-Uncertainty）**
每条手势观测携带 `(onset, recog, Γ)`；在 `t ∈ [onset, recog + L_max]` 内，控制必须对 `I(t) = λ(t) ∪ ⋃_{o 在途} Γ_o` 保持安全。**只有**当在途观测落定、且以 ≥1-α 的 conformal 覆盖排除了 SP 意图后，才允许释放该保守约束。延迟被显式建模为不确定集，而非被忽略或简单补偿。

**P38 安全意图锁存律（Safety-Positive Latching）**
SP = {STOP, YIELD, SLOW, RETREAT} 一旦被识别，**回溯到 onset 生效并锁存**至 `TTL_latch`；解除锁存需 `q ≥ q_clear` ∧ 模态佐证 ∧ 明确 clear 手势。SN = {GO, APPROACH, SPEEDUP, HANDOVER_ACCEPT} **仅从 recog 向前生效、不回溯**，且受 TTL 约束。故延迟对 SP 只增约束、对 SN 只减收益——**时间语义非对称 ⇒ 延迟单调安全**。

**P39 实时预算分离律（Real-Time Budget Separation）**
硬实时安全路径（反射减速/急停）**手势无关**且 `WCET_reflex < T`；手势识别在软实时路径运行，预算 `C_g` 满足 `WCET_reflex + C_g ≤ T`，且手势只能**追加**约束。管线超时 ⇒ 降级到"锁存态 + 反射"，**绝不等待手势**。两次更新之间的连续时间安全由 CBF 保证。

## 3. 与基线的接口（如何退化）

- LAIH 失效（延迟模型不可信）⇒ 所有未决手势按 SP 处理（更保守），退化为 v21 GIC 逐帧语义的子集；
- TCIM 失效（置信序列失配）⇒ 退回 v21 固定阈值 conformal，同时上调 `q_high`（更保守）；
- SPLSM 失效 ⇒ 所有意图按 SP 处理、只减不增，等价于全域锁存；
- MCGS 超时/降级 ⇒ 锁存态 + 反射减速，等价 v21 静态合规默认；
- CBF-IG 失效 ⇒ 回退 v21 DCL 域过滤 + 反射急停；
- AGH（前瞻识别）失效 ⇒ 无提前量，退回 LAIH 的普通在途窗口；
- 全失效 ⇒ 完全回退 v21 ⇒ `Exec_v22 ⊆ Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19 ⊆ Exec_v18`（引理 168）。
- **安全继承**：LAIH 只把延迟变成更宽的约束、SPLSM 只回溯/锁存 SP、CBF-IG 只交约束、MCGS 只降级到锁存态、TCIM 只收紧门槛；任意失效都向更保守方向退化。

## 4. 预期贡献

1. **延迟感知意图时域**：把识别延迟从"需要补偿的噪声"变成"可规划的显式意图不确定集"，给出在途窗口内保持安全、落定后释放的严格语义；
2. **时间语义非对称锁存**：SP 回溯锁存 / SN 前瞻过期的形式化，并证明"延迟单调安全"——晚到的 STOP 仍回溯生效，晚到的 GO 只是损失活性；
3. **连续时间安全与手势速率解耦**：锁存意图编译为 CBF，两次更新间前向不变，安全不依赖手势到达率；
4. **混合关键性实时调度**：手势无关的硬实时反射路径 + 软实时手势路径的 WCET 预算、超时降级与无抖振切换；
5. **anytime-valid 时序 conformal**：在可选停时与分布漂移下维持 1-α 的**持续**覆盖，而非逐批覆盖；
6. **时间戳停止证书 TSC 与 HPC++**：把手势的 onset/recog/latch/补偿全链纳入可机械复核的证书体系。

## 5. 本轮最大风险

**一句话**：整套实时安全论证擅长处理"手势**会迟到**"，却把"手势**根本没被识别**"交给反射路径兜底——一旦安全负意图（许可）的**撤销手势**被漏识别，锁存态会继续用过期许可放行，而系统在形式上完全合规：框架能证明"晚到的 STOP 仍安全"，却无法证明"没被看见的 STOP"。

```python
# IP-431 Latency-Aware Intent Horizon
class LatencyAwareIntentHorizon:
    def __init__(self, gic, latency_model, epsilon=0.01):
        self.gic = gic
        self.lat = latency_model            # L 分位数表；L_max = quantile(1-epsilon)
        self.eps = epsilon
        self.inflight = []
        self.latched = SafetyPositiveLatch()

    def observe(self, g, t_recog):
        onset = g.onset_timestamp            # 由轨迹起点回溯估计
        self.inflight.append(InFlight(
            gid=g.id, onset=onset, recog=t_recog,
            Lmax=self.lat.quantile(1 - self.eps), gamma=g.gamma_set))
        self.latched.apply(g.intent, onset, t_recog, g.q, g.modalities)

    def intent_uncertainty(self, t):
        I = set(self.latched.active_intents(t))
        for o in self.inflight:
            if o.onset <= t <= o.recog + o.Lmax:
                I |= o.gamma                 # 在途：并集，宁可保守
        return I

    def release_ok(self, t):
        # 只有落定且 conformal 覆盖排除了 SP，才允许释放保守约束
        settled = [o for o in self.inflight if t > o.recog + o.Lmax]
        self.inflight = [o for o in self.inflight if o not in settled]
        return not (self.intent_uncertainty(t) & SP)

# IP-432 Temporal Conformal Intent Monitor
class TemporalConformalIntentMonitor:
    def __init__(self, alpha=0.01):
        self.alpha = alpha
        self.e = BettingEProcess()           # 非负鞅，e_0=1
        self.scores = []

    def update(self, score, t):
        self.scores.append(score)
        self.e.update(score)

    def coverage_ok(self):
        return self.e.value() < 1.0 / self.alpha   # 未越过 ⇒ 维持 1-alpha

    def conformal_set(self, probs):
        q = time_uniform_quantile(self.scores, self.alpha)
        return {c for c, p in probs.items() if p >= q}

    def drift_trigger(self):
        return not self.coverage_ok()        # 触发重校准 / 上调 q_high

# IP-433 Safety-Positive Latching State Machine
class SafetyPositiveLatch:
    def __init__(self, q_clear=0.9, ttl=2.0, min_modalities=2):
        self.q_clear, self.ttl = q_clear, ttl
        self.min_modalities = min_modalities
        self.latches = {}

    def apply(self, intent, onset, t_recog, q, modalities):
        if intent in SP:
            self.latches[intent] = Latch(onset, t_recog, t_recog + self.ttl)
        elif (intent in SN and q >= self.q_clear
              and len(modalities) >= self.min_modalities):
            # SN：仅从识别时刻前瞻生效，绝不回溯
            self.latches[intent] = Latch(t_recog, t_recog, t_recog + self.ttl)
        return self

    def active_intents(self, t):
        return {i for i, l in self.latches.items() if t <= l.expiry}

    def clear(self, intent, t, q, modalities):
        if q >= self.q_clear and len(modalities) >= self.min_modalities:
            self.latches.pop(intent, None)

    def retro_window(self, intent):
        l = self.latches[intent]
        return (l.onset, l.t_recog)          # 供 TSC 记录 / 补偿判定

# IP-434 Mixed-Criticality Gesture Scheduler
class MixedCriticalityGestureScheduler:
    def __init__(self, period=0.02, gesture_budget=0.01,
                 reflex_wcet=0.002, miss_limit=5):
        self.T, self.Cg, self.Cr = period, gesture_budget, reflex_wcet
        self.miss_limit, self.misses = miss_limit, 0

    def tick(self, t, gesture_job, reflex_job):
        # 硬实时反射先跑，WCET 有界，绝不等待手势
        reflex_job.run_bounded(self.Cr)
        ok = gesture_job.try_run(deadline=t + self.Cg)
        if not ok:
            self.misses += 1
            return "LATCH_FALLBACK"
        return "OK"

    def mode(self):
        return ("GESTURE_ACTIVE" if self.misses < self.miss_limit
                else "LATCH_ONLY")

# IP-435 CBF Intent Governor
class CBFIntentGovernor:
    def __init__(self, cbf, alpha_fn, tau_stop=0.3):
        self.cbf, self.alpha_fn, self.tau_stop = cbf, alpha_fn, tau_stop

    def constraints(self, x, I):
        cons = [self.cbf.condition(x, self.alpha_fn)]   # 手势无关的基础约束
        if "STOP" in I:
            cons.append(stop_within(x, self.tau_stop))  # v -> 0 in tau_stop
        if "YIELD" in I:
            cons.append(yield_region_constraint(x))
        if "SLOW" in I:
            cons.append(speed_cap(x, v_slow))
        return cons                                     # U_cbf = 交集

    def solve(self, x, u_ref, I):
        u = qp_min_norm(u_ref, self.constraints(x, I))
        if u is None:
            return emergency_brake(x), "CBF_INFEASIBLE->ESTOP"
        return u, "OK"

    def invariant_between_updates(self, x, I):
        # I 在两次更新间不变 ⇒ CBF 保证前向不变，与手势到达率无关
        return self.cbf.forward_invariant(x, self.constraints(x, I))

        pred = self.forecaster(trajectory, self.horizon)
        # 仅允许提前识别 SP；预测不确定性并入 Γ，绝不提前授予许可
        return pred if pred.intent in SP else None
```

## 3. 推导

**引理 163（延迟不确定集的覆盖与释放）** 设 onset 估计误差 ≤ δ_on、延迟以 ≥1-ε_lat 不超过 `L_max`，且 TCIM 的 conformal 集满足 `P(真意图 ∈ Γ) ≥ 1-α`（可选停时下亦成立，见引理 167）。则对 `t ∈ [onset, recog+L_max]`，真意图以 ≥1-α-ε_lat 落入 `I(t)`。因 `I(t)` 取并集是保守超集，安全不依赖覆盖成立；而**释放**保守约束需要 `I(t) ∩ SP = ∅`，由覆盖性推得 `P(真意图 ∈ SP) ≤ α+ε_lat`，即假释放有显式上界。∎

**引理 164（锁存单调安全）** SP 意图回溯至 onset 并锁存，其在 `TTL_latch` 内只能被 `q ≥ q_clear` ∧ 模态佐证的显式 clear 移除；SN 意图从 recog 起前瞻且按 TTL 过期，不回溯。故在任意两次 clear 之间，admissible 控制集 `U(t)` 对 SP 只减不增；延迟使 SP 更早（回溯）生效，只会收紧 `U(t)`。于是 `Exec_v22 ⊆ Exec_v21`，且延迟对安全单调。∎

**引理 165（CBF 更新间安全）** 设 `h` 为有效 CBF、`α` 为 class-κ 函数，`U(t)=⋂_{i∈λ(t)} {u : ḣ + α(h) ≥ 0}`。若 `u(t) ∈ U(t)`，则 `h(x(t)) ≥ 0` 前向不变。两次手势更新之间 `λ(t)` 不变 ⇒ `U(t)` 不变 ⇒ 安全与手势到达率解耦；更新时 SP 只使 `U` 收缩，SN 解除仅回到 v21 基线 `U_v21`，故 `U(t) ⊆ U_v21(x)`。∎

**引理 166（混合关键性降级）** 若 `WCET_reflex + C_g ≤ T`，则每个控制周期内反射路径必完成且手势路径不侵占其预算。手势超时降级为"锁存态 + 反射"；由引理 164，锁存态安全；由引理 165，锁存态下 CBF 仍前向不变。故安全不依赖手势路径是否满足截止时间，降级单调且无抖振（模式切换有 `miss_limit` 滞回）。∎

**引理 167（anytime-valid 时序 conformal）** 赌注 e-process `e_t` 为非负鞅且 `E[e_0]=1`，由 Ville 不等式 `P(∃t: e_t ≥ 1/α) ≤ α`，故置信序列在可选停时下维持 1-α 覆盖。分布漂移使 `e_t` 越界时触发重校准并上调 `q_high`，保证漂移后覆盖恢复到 1-α（保守方向）。∎

**引理 168（v22 整体安全继承）** 同快照、同规则库、同机器人集合下：LAIH 只把延迟变成更宽约束（163）、SPLSM 只回溯/锁存 SP（164）、CBF-IG 只交约束（165）、MCGS 只降级到锁存态（166）、TCIM 只收紧门槛（167）、AGH 只提前 SP（不提前 SN）。故 `Exec_v22 ⊆ Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19 ⊆ Exec_v18`。∎

**引理 169（回溯补偿的可见性）** 对 SP 意图，回溯窗口 `[onset, recog]` 内的运动按"已停止"约束复核；任何越界记入 TSC 的补偿事件并触发 SafeStop，故不存在"迟到的停止被静默接受"——晚到 STOP 的每一毫秒都可被审计与追责。∎

## 7. 已知风险与失效模式

1. **撤销手势漏识别**（最大风险，见第 8 节）：κ_recall 对非常规手势/遮挡/逆光系统性失效，SN 锁存继续放行。缓解：反射路径手势无关兜底（E819）、SN 的 TTL 宁短勿长、独立传感器冗余、撤销手势多模态确认。
2. **延迟模型失配**：`L_max` 在负载/设备切换下失真，在途窗口过窄致晚到 STOP 漏保护。缓解：分层标定（E802）、在线尾延迟监控、失配即按 SP 处理。
3. **CBF 可行性与急停抖动**：STOP 约束可能与动力学冲突导致频繁 ESTOP。缓解：`τ_stop` 与执行器能力联合标定、加可行性裕度与滞回（E812）。
4. **模式抖振**：MCGS 在 GESTURE_ACTIVE / LATCH_ONLY 间振荡。缓解：miss_limit 滞回 + 随机退避（E816）。
5. **时钟同步误差**：回溯/前瞻判定依赖单调时钟与 skew 上界。缓解：单调时钟、skew 显式入证书、超界拒签 TSC（E817）。
6. **活性成本**：在途窗口与 SP 锁存叠加使密集人流区变慢。缓解：conformal 及时排除 SP（E804）、AGH 提前量、SN 高门槛快速放行。
7. **AGH 假阳性**：提前识别误判为 SP 只损失活性（可接受），但若被滥用于 SN 则危险。缓解：硬编码 AGH 仅对 SP 生效（E820）。

## 8. 本轮最大风险

**一句话**：整套实时安全论证擅长处理"手势**会迟到**"，却把"手势**根本没被识别**"交给反射路径兜底——一旦安全负意图（许可）的**撤销手势**被漏识别，锁存态会继续用过期许可放行，而系统在形式上完全合规：框架能证明"晚到的 STOP 仍安全"，却无法证明"没被看见的 STOP"。
