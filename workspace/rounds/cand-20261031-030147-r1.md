# 第 13 轮 · DUET：双臂角色图 × 少样本角色脚本 × 社会性让位

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本轮是灵感循环新周期的第 1 轮，也是状态文件的第 13 轮；三个随机词是 **「双臂协作」「少样本学习」「社会影响」**。不推倒第 12 轮 CHUNK-SERVO，而是把它从“单臂最后 3 厘米的伺服”升级为“双臂角色 + 少样本记忆 + 人”的执行层。

## 0. 先给结论

- 排行榜的 29.7% 不是实测 SOTA：`leaderboard_data.json` 由 `gen_leaderboard.py` 生成，详情页视频全是占位，任务成功率不是 10 次试验应有的 10% 整数倍；8 个模型的任务成功率画像平均相关仅 **0.098**。它是“预览难度信号”，不是“任务难度表”[S3][S4]。
- 头部方案已经不缺“大”：MolmoAct2 有 720h 双臂数据、WALL-OSS-0.5 有 20+ 具身预训练、DreamZero 有 14B 视频世界模型，但预览分仍在 28%–30% 量级。真正缺的是**把双臂角色、少样本记忆和人的存在接进控制环**。
- 本轮主押注 **DUET**：同一个官方 WLA 输出双臂动作；从 33k 成功演示中检索 **角色脚本**（谁 LEAD、谁 STABILIZE、何时 BOTH_CARRY/HANDOVER）；用确定性投影把 VLA 的 21D 动作约束成角色一致的动作；用 **HUMAN-YIELD** 状态机处理“临时改变物品位置/人手进入”的人为干扰。
- 三个词分别对应三个可验证子点：**BRG**（双臂角色图，回答“谁来做/谁稳住”）、**FS-Role**（少样本角色脚本检索，回答“没见过的东西怎么套用旧角色”）、**HUMAN-YIELD**（社会性让位，回答“人来了怎么办”）。
- 一句话押注：**用官方 WLA 做单模型双臂规划，用 33k 演示检索出的角色脚本做确定性投影，用让位状态机处理人为干扰——把“谁来做、谁稳住、谁让位”显式接进控制环。**

## 1. 本轮核实的事实

| 4 | Spirit-v1.5 | VLAGO | 25.9% | 34.4 | 45.19 s |
| 5 | DM0 | Embodied AI Institute | 23.5% | 31.7 | 45.11 s |

| 8 | GR00T N1.5 | Humanoid Dynamics | 20.5% | 28.1 | 44.71 s |

三个可复现的“预览”证据：

1. **生成来源**：JSON 顶层写着 `"generated_from": "gen_leaderboard.py"`；这不是评测日志，是生成脚本[S3]。
2. **视频占位**：MolmoAct2、WALL-OSS-0.5、DreamZero、GigaBrain-0 的详情页，32 个任务全部显示“测试视频占位，后续可替换为真实视频文件”[S4]。
3. **统计指纹**：每个模型的 `avg_step_score` 与 `avg_success_rate` 线性拟合 **R²=1.000000（8/8）**；成功率出现 6.3、9.03、11.33、42.0 等值，不是 10 次试验的 0/10、1/10…；把 8 个模型当变量、32 个任务当样本，模型间任务成功率平均相关仅 **0.098**。真实评测不会这么“干净”。

**结论**：可以把榜单当“哪些方向有人做、大致什么量级”的先验；不能把某任务 9% 当成真实难度，也不能把 29.7% 当成不可超越的 SOTA。

### 1.2 规则：单模型、32 任务、10 次、5 类泛化、180 秒

官方参赛手册（飞书 docx，2026-10-31 通过 `r.jina.ai` 抓取；以官方最终版本为准）核实[S6][S7]；端口约定来自提交 README[S9]：

| 项 | 规则 |
|---|---|
| 模型 | **所有任务须基于同一模型完成，不得混合多个模型一起测试**；模型类型不限（World Model、VLA 均可） |
| 任务 | 32 项桌面任务；抓取、放置、双手协作是核心能力 |
| 次数 | 每任务 **10 次独立运行** |
| 泛化 | 5 类各 2 次：位置、干扰物、桌面背景、未见物品、**人为干扰** |
| 人为干扰 | 规则举例是“临时改变物品位置等”，不一定出现人手；考察鲁棒性与抗干扰能力 |
| 时限 | 单次真机执行上限 **180 s** |
| 排名 | 先比 32 任务总平均成功率；相同看总平均步骤分；再相同看**更早提交** |
| 部署 | 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态隔离 |
| 测试通道 | 另有**不计分的单任务测试通道**，可测单任务成功率/步骤分 |

**对本方案的约束**：

- 不能用一个 LLM 做高层规划、再用一个 VLA 做执行；这有“混合多个模型”的解释风险。
- 不能为每个任务训一个策略；规则要求通才单模型。
- 必须每端口独立、CPU 轻量、GPU 可共享；不能假设只有一台机器人。
- 单任务通道是唯一安全的 A/B 场地；正式提交前不要把 320 trials 浪费在未过门的模块上。

### 1.3 接口：四路 RGB、无深度/力/触觉、固定 chunk

提交模板 README（2026-10-31 复核）给出[S9]：

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640** |
| 本体 | 双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str` |
| 动作空间 | `control_space` 仅 `"joint"` 或 `"ee"`，二者互斥 |
| EE 动作 | 左/右 `ee_pose_gripper_base [6]`（绝对目标位姿，xyz+rpy，base 系） |
| 共享动作 | 左/右 `gripper [1]`、`pivot [7]` |
| chunk | `action_chunk_size` 在 metadata 中固定，≥1；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action` |
| token | `metadata.token` 握手校验一次；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile、audio** |
| 监控 | 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分 |

**关键推论**：

- 若 `action_chunk_size=30`、控制 30Hz，一次 `get_action` 后有 **1 秒开环**；chunk 内没有新观测，也没有打断机制。视觉伺服/让位要生效，必须把 metadata 的 chunk 降到 3–8 步，或接受 1 秒的“盲区”。
- 四路 RGB 足够做 2D 视觉伺服、头部双目深度、腕部局部对齐；不够做力控/触觉闭环。
- `action_chunk_size` 是 metadata 固定值，不能假设可以在一次 episode 内动态改；本报告默认 **H=5**，用单任务通道验证 H=5 vs H=8。

**共同瓶颈**（不是“模型不够大”）：

1. **开环 chunk**：MolmoAct2 自己承认整批执行不重规划；UniBot 的 chunk 内也没有新观测。接触误差在 1 秒内无人纠正。
2. **双臂角色未显式化**：21D 动作把两只手当联合向量；没有“谁 LEAD、谁 STABILIZE、何时交换”的结构。接触时两只手都可能漂。
3. **少样本记忆未进入控制**：33k 演示主要被当成 BC 训练集；没有被当成“角色脚本库”在测试时检索。
4. **人未被建模**：人为干扰是 20% 的 trials，但多数策略把人的进入当成视觉噪声或直接超时；没有让位/护持/交接的社会行为。
5. **世界模型不解决接触**：视频预测可以告诉你“杯子应该挂上去”，但不能保证 2 mm 的孔位对齐；最后 3 厘米仍是控制问题。

## 2. 诊断：三个词为什么正好对应三个缺口

### 2.1 双臂协作：动作是 21D，但角色是 0D

UniBot 的 EE 动作是 `[左 EE 6, 左夹爪 1, 右 EE 6, 右夹爪 1, pivot 7]`。这是一个**联合向量**，不是**协调结构**。对下面这些任务，真正决定成败的是角色，而不是单臂轨迹：

- **STABILIZE + LEAD**：一手扶住容器/底座，另一手插入/拧/拉。例：PlugInEthernet、Unlock、SyringeWaterTransfer、ZipUp。
- **BOTH_CARRY**：两手共同搬运/展开，保持相对位姿。例：FoldTowel、ArrangePlates、PaperCupStacking。
- **HANDOVER**：物体从一手交到另一手。例：PackBag、ToolboxStorage 的某些阶段。
- **IDLE**：一只手退到安全位，避免遮挡/碰撞。例：HangCup 的挂杯阶段。

我们用 32 个数据集的 `action.*.ee_pose_gripper_base` 统计构造了一个**启发式双臂指数 BI\***（不是官方指标）：

```text
s_L, s_R = 左/右 EE 位置三轴标准差的均值
g_L, g_R = 左/右夹爪动作标准差
bal      = 2·min(s_L,s_R)/(s_L+s_R)
gbal     = 2·min(g_L,g_R)/(g_L+g_R)
BI*      = 1000 · min(s_L,s_R) · bal · gbal
```

它与上一轮 BI 的 Spearman ρ≈0.78，排序稳健。高分组（BI\*≥55）包括 OrganizeTools 66.5、StorePaddle 63.8、ArrangePlates 61.9、OrganizeBookshelf 59.7、FoldTowel 59.6、PaperCupStacking 56.1；低分组包括 HangCup 7.3、SpellRobot 10.0、PickOutBatteries 14.2。完整表见产物区。

**但不能只看 BI\***。我们抽样了 8 个任务（每任务约 80–120 帧，HF datasets-server `rows` API，2026-10-31）看“双手是否同时夹住/同时运动”：

| 任务 | both active | both grippers non-open | BI\* | 解释 |
|---|---:|---:|---:|---|
| FoldTowel | 0.59 | 0.16 | 59.6 | 两手都在动，但不一定同时夹住；更像“共同展开/对折” |
| ZipUp | 0.32 | **0.92** | 38.7 | 两手长期夹住袋子，但只有一只在拉；典型 STABILIZE+LEAD |
| SyringeWaterTransfer | 0.74 | 0.33 | 51.5 | 一手持针筒、一手推活塞；强角色分工 |
| Unlock | 0.55 | 0.67 | 37.6 | 一手固定锁、一手转钥匙；角色分工 |
| HangCup | 0.74 | **0.00** | 7.3 | 只有一只手夹杯；不是真正双手协调 |
| FruitSorting | 0.80 | 0.00 | 43.2 | 两手都动，但不同时夹；可能是交替搬运 |
| PackBag | 0.77 | 0.75 | 54.8 | 两手同时参与撑袋/装物；强 BOTH_CARRY |
| ToolboxStorage | 0.72 | 0.00 | 49.8 | 两手都动，但不同时夹；更像顺序角色 |

**结论**：双臂任务不是“两只手都动”这么简单。至少有三类协调模式：**角色分工**（ZipUp/Unlock/Syringe）、**共同搬运**（FoldTowel/PackBag/ArrangePlates）、**伪双臂**（HangCup/FruitSorting，另一只手只是辅助或空闲）。一个统一的 21D 策略很难在三类模式间切换；角色图可以。

### 2.2 少样本学习：33k 演示是训练集，不是“记忆”

33k 集、169 小时是很大的训练集，但对**未见物品**泛化仍然不够：规则明确说“引入与任务目标同类但外观明显不同的物品（不同颜色、形状、材质）”2 次/任务。模型没见过新物体的外观，但**角色脚本**（先扶住、再对齐、再插入、再释放）是物体无关的。

已有工作证明这条路径可行：

- **BUDS**：把双臂分解为“稳定臂 + 操作臂”，只用 **20 个演示**，在 4 个真实双臂任务上达到 **76.9%** 成功率，对类内新物体 **52.7%**；比非结构化 BC 稳定臂高 56.0%。它证明“角色分解”能显著降低数据需求[S24]。
- **BiCICLe**：把双臂建模成 leader-follower 多智能体，用**免训练 LLM 的 in-context learning**做 few-shot，13 个 TWIN 任务平均 **70.5%**，超过多数监督方法。它证明“leader-follower + few-shot”有效，但用了第二个模型（LLM）[S25]。
- **VLBiMan**：**单个人类演示**、VLM 锚定、无需重训，支持同步/异步双臂和外部扰动；ICLR 2026[S26]。
- **YOTO/YOTO++**：**单个人类视频**提取 3D 手部运动、关键帧蒸馏、闭环视觉对齐；YOTO 为 RSS 2025，YOTO++ 为 TPAMI 2026[S27]。
- **DuoBench**：2026 年的双臂 benchmark 显示，当前策略在**早期交互、并行双臂执行、sim-to-real** 上仍然吃力；这正好对应角色图要解决的阶段[S32]。

**我们的差异**：不训练第二个 LLM/策略，不做 full one-shot policy learning；把 33k 演示切成人可读的**角色脚本**，测试时检索 3–5 条，作为同一个 VLA 的**语言条件 + 确定性约束**。这是“少样本”在单模型规则下的合规形态。

### 2.3 社会影响：人为干扰是 20%，但多数策略只会“停”或“撞”

规则的人为干扰是 5 类泛化之一，占 2/10 trials；举例是“临时改变物品位置”。这意味着两件事：

1. **不一定是人手进入**：可能是评测者在任务中途把物体挪走/挪偏。策略需要**暂停—重新观察—重新定位—继续**，而不是盲目执行旧 chunk。
2. **也可能是人手进入**：如果是人把物体拿走/递回，机器人需要**让位、护持、交接**，而不是继续伸向人的手。

社会影响不只是“比赛加分”：

- **微观**：在家庭/医院/共享工作台，机器人必须能读懂“人正在拿这个东西”，否则再高的任务成功率也不安全。
- **宏观**：双臂机器人 + 少样本角色记忆可以降低数据采集成本，让中小团队也能部署；但也会带来“过度信任”“隐私”“误让位导致任务失败”等问题。我们需要在方案里写清楚边界，而不是只讲好处。

已有 **SocialVLA** 在 Unitree G1 上用人的语音/表情/动作做失败检测与恢复，证明“社会感知”可行；但它需要音频/视觉反应数据，且是一个独立的感知网关（第二个模型），在 UniBot 的单模型/无音频 API 下不能直接用[S29]。我们的做法是**确定性让位**：只用本体 + 视觉运动/遮挡 + 任务状态，不识别人的身份，不录音，不上传。

## 3. DUET 方法

### 3.1 总架构

```text
离线（一次性）：
  33k demos
    │  自动分段：夹爪开合 + EE 速度 + 高度 + 接触邻近
    ▼
  角色脚本库  Script = {task, phase, role_L, role_R, g_L, g_R,
                        T_LR*, w_support*, object_desc, duration}
    │  每条脚本 3–5 个 exemplar；32 任务 × 3–6 阶段
    ▼
  检索索引（task ID + 阶段 + 物体几何/颜色 + 初始 EE 相对位姿）

在线（每 H=5 步）：
  四路 RGB + 本体 + 语言
    │
    ▼
  官方 WLA（唯一学习模型）
    │  输出 30 步双臂 chunk A = [a_L, g_L, a_R, g_R, pivot]
    ▼
  FS-Role 检索 top-3 脚本
    │
    ▼
  角色推断（DTW 对齐当前 EE/夹爪轨迹到脚本）
    │  role_L, role_R, phase, confidence
    ▼
  BRG 投影（确定性 QP/虚拟夹具）
    │  STABILIZE → 保持/柔性支撑
    │  LEAD      → 保留 VLA，限速/限幅
    │  BOTH_CARRY→ 相对位姿约束
    │  HANDOVER  → 夹爪时序 + 交接位姿
    │  IDLE      → 安全收臂
    ▼
  HUMAN-YIELD 监督（视觉运动/遮挡 + 任务状态）
    │  MONITOR → SLOW → YIELD/HANDOVER → RESUME
    ▼
  执行 H=5 步 → 新观测 → 回到 WLA
```

**一句话**：WLA 决定“做什么”；FS-Role 决定“用哪套角色脚本”；BRG 决定“谁来做/谁稳住”；HUMAN-YIELD 决定“何时让”。

### 3.2 BRG：双臂角色图

角色集合：

| 角色 | 含义 | 确定性约束 |
|---|---|---|
| `LEAD` | 主动作臂：接近、抓取、插入、拧、拉 | 保留 VLA 动作；限速/限幅；末端接近方向由脚本给先验 |
| `STABILIZE` | 支撑臂：扶住容器/底座/物体 | 保持当前或脚本支撑位姿 `w*`；小范围柔顺；夹爪按脚本闭合 |
| `BOTH_CARRY` | 双手共同搬运/展开 | 保持相对位姿 `T_LR*`；两臂动作投影到约束流形 |
| `HANDOVER` | 物体从一手交到另一手 | 固定时序：支撑臂闭合 → 操作臂张开 → 交接位姿 → 角色交换 |
| `IDLE` | 该臂不参与，退到安全位 | 收臂到安全姿态，避免遮挡/碰撞 |

**角色转移图**（简化）：

```text
IDLE ──need_support──▶ STABILIZE ──contact_made──▶ LEAD
  ▲                        │                         │
  │                        │ need_carry              │ need_handover
  │                        ▼                         ▼
  └──── release ◀──── BOTH_CARRY ◀──── handover_ready ──── HANDOVER
```

转移守卫是确定性的：夹爪开合、EE 速度、脚本阶段、视觉接触邻近、人体/障碍物状态。没有学习型分类器。

**投影数学**：

设 VLA 原始 chunk 为 `A_t = {a_{t+i}}`，`a = [a_L, a_R]`。对每个角色：

- `STABILIZE`：
  ```text
  a_arm = clip( K_p (w* − x_t) − K_d v_t , v_max )
  ```
  若 `w*` 不可用，则保持当前 EE 位姿（零速度），只允许小角度柔顺。
- `LEAD`：
  ```text
  a_arm = clip( a_arm^VLA, v_max, workspace )
  ```
- `BOTH_CARRY`：
  ```text
  min_{a_L,a_R}  ||a_L − a_L^VLA||² + ||a_R − a_R^VLA||²
  s.t.           T_L(a_L)⁻¹ T_R(a_R) = T_LR*
                 joint/velocity/workspace limits
  ```
  在当前位置线性化，解一个小 QP；或把相对位姿误差 `ΔT = T_LR* (T_L⁻¹T_R)⁻¹` 均分给两臂（闭式虚拟夹具）。
- `HANDOVER`：
  ```text
  phase 1: g_stabilize ← close, g_lead ← open
  phase 2: both → handover pose (脚本给)
  phase 3: g_stabilize ← open, g_lead ← close
  phase 4: swap roles
  ```
- `IDLE`：安全收臂，不参与 VLA 的联合动作。

**为什么不是第二个模型**：角色标签来自离线规则/人工标注；投影是 QP/控制律；没有学习权重。VLA 仍是唯一学习模型。

### 3.3 FS-Role：少样本角色脚本

**离线分段**：

对每条演示，按以下信号切阶段：

- 夹爪开合沿时间的变化（`g_L(t), g_R(t)`）；
- EE 速度/高度/到物体的距离；
- 任务语言中的子目标（如“抓住—抬起—插入—释放”）；
- 人工抽检 5 个任务，校正自动分段。

每个阶段生成一条脚本：

```text
Script = {
  task, phase,
  role_L ∈ {LEAD, STABILIZE, BOTH_CARRY, HANDOVER, IDLE},
  role_R ∈ {...},
  g_L*, g_R* ∈ {open, close},
  T_LR* (BOTH_CARRY 时),
  w_support* (STABILIZE 时),
  object_desc = {bbox 尺寸, 长宽比, 颜色直方图, 初始位姿},
  duration, approach_dir
}
```

每个任务每个阶段保留 **3–5 个 exemplar**（按初始物体位姿/背景聚类）。32 个任务、每任务 3–6 阶段，脚本库规模约 **300–600 条**，纯 JSON/NumPy，毫秒级检索。

**在线检索**：

- 查询：任务 ID（语言已知）+ 当前 phase（DTW 估计）+ 物体几何/颜色 + 当前 EE 相对位姿。
- 打分：
  ```text
  score = w1·task_match + w2·phase_match + w3·object_sim
        + w4·pose_sim + w5·role_prior_match
  ```
- 取 top-3；若 top-1 与 top-2 分数接近且角色冲突，**不投影**，回退 VLA 原始动作。
- 检索到脚本后，把 `role_L/role_R` 写进语言提示（例如 “Fold the towel. Left arm lead, right arm stabilize.”），让同一个 VLA 在训练/微调时见过角色条件。

**少样本泛化的关键**：角色脚本是**物体无关**的。新物体只影响“抓哪里/怎么对齐”，不影响“谁扶、谁插、何时换手”。所以即使物体外观没见过的，角色先验仍然可迁移。我们用物体几何/颜色做检索，不用学习型 6D 位姿网络。

### 3.4 HUMAN-YIELD：社会性让位

**检测**（确定性，不用学习型人体检测器）：

- 头部右高/双目：对工作区做运动能量/背景差分；用当前 EE 投影遮掉机器人自身运动；大块新运动进入工作区 → 触发。
- 腕部相机：突然遮挡/亮度突变/近景大块肤色/纹理 → 触发。
- 任务状态：物体在脚本预期位置消失/被移动 → 触发“环境变化”。
- 本体：EE 速度被外部阻挡/跟踪误差突增 → 触发（无力的估计，只能用位置误差）。

**状态机**：

| 状态 | 触发 | 行为 | 退出 |
|---|---|---|---|
| `MONITOR` | 正常 | 正常执行 | 检测到人/物体变化 |
| `SLOW` | 人靠近工作区边缘 | 速度降到 50%，保持夹持 | 人离开或进入 |
| `YIELD` | 人进入可达工作区 | 暂停 LEAD，STABILIZE 保持/轻放，收臂 3–5 cm | 人离开/物体稳定 |
| `HANDOVER` | 人伸手向机器人持有的物体 | 张开夹爪，把物体递到人可拿的位姿，等待 | 人接管/离开 |
| `RELOCALIZE` | 物体被挪动但人已离开 | 重新观察，重检索脚本，CHUNK-SERVO 重新对齐 | 对齐成功 |
| `RESUME` | 障碍清除 | 从当前状态重新规划；必要时重抓 | 回到 MONITOR |

**安全边界**：

- 让位等待有上限（例如 3 s）；超时后轻放物体并重新规划，不无限等待。
- 交接只在低速、低高度、夹爪闭合度足够时触发；不把尖锐/易碎物递到人手正前方。
- 不做身份识别、不录音、不保存人脸；视觉处理在本地。
- 检测不到人时，不声称“绝对安全”；只做减速/限幅。

**社会影响评估**：

- 正面：减少人机碰撞、提高共享工作台的可接受度；让位/交接比“停在原地”更可读；少样本角色记忆降低数据成本。
- 负面/风险：误让位导致超时；误交接导致掉落；人可能过度信任机器人；视觉检测在遮挡/光照变化下漏检。
- 缓解：有界等待、低速交接、失败回退、单任务通道统计误触发率；在提交材料中明确“不是安全认证”。

### 3.5 角色感知的 chunk 调度

CHUNK-SERVO 的“30 步规划、5 步执行”保留，但按角色调整有效视野：

| 角色 | 执行块 H | 理由 |
|---|---:|---|
| `LEAD` 接近/插入 | 3–5 | 需要最快反馈，接触误差累积最快 |
| `STABILIZE` 保持 | 8–10 | 目标位姿变化慢，可长一点，省 RTT |
| `BOTH_CARRY` | 5–8 | 两臂相对位姿要同步，太长会漂 |
| `HANDOVER` | 3–5 | 夹爪时序不能错 |
| `IDLE` | 10–15 | 不需要频繁调用，省算力 |

**实现**：metadata 的 `action_chunk_size` 固定为一个安全值（建议 5）；VLA 仍可输出 30 步计划，执行层只取前 H 步；若某些角色需要更长，用 hold/零速度填充剩余动作，而不是改变 metadata。是否允许这样“截断+填充”需在单任务通道用 `example_client.py` 验证；若 evaluator 对 chunk 形状有额外检查，回退固定 H=5。

### 3.6 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 角色标签/脚本只离线生成；线上只有 VLA | 最低 | 保守首选 |
| C2 确定性控制器 | BRG 投影/让位状态机无学习权重；VLA 是唯一学习模型 | 低；需向官方说明 | 主推 |
| C3 同 checkpoint 特征 | 物体描述子用 VLA 同一 checkpoint 的 encoder，不加载第二个模型 | 低–中；需说明 | 需要强描述子时用 |

**禁止**：第二个学习策略、LLM 规划器、独立视觉编码器做在线决策、TwinVLA/VLA-Fabric 式多 VLA[S30][S31]、SocialVLA 式独立感知网关。它们可能更强，但在“同一模型”规则下有解释风险。

## 4. 实验门 G0–G8

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | 角色分段是否可信？ | 5 个任务人工抽检，自动分段与人工角色一致 ≥85% | 只用手工标注的 5 任务，不扩到 32 |
| G1 | 脚本检索是否有效？ | top-3 含正确 phase/role ≥80%；物体相似度与角色不冲突 | 退回任务级固定脚本 |
| G2 | 投影是否收敛？ | BOTH_CARRY 相对位姿误差 ≤5 mm/2°；STABILIZE 漂移 ≤3 mm | 降增益/只对 STABILIZE 生效 |
| G3 | 单任务是否涨点？ | 5 任务各 5 次 A/B：≥3 任务 +10pp；FoldTowel 不回归 >5pp | 不提交 BRG/FS-Role 版本 |
| G4 | 让位是否安全？ | 脚本人手/物体移动：检测 ≤300 ms；恢复 ≥60%；0 碰撞 | 只做减速/暂停，不做交接 |
| G5 | 延迟是否可接受？ | p99 ≤200 ms；timeout 不升 | H=8、关投影、降分辨率 |
| G6 | 32 任务干跑是否稳定？ | N 端口隔离、reset 干净、内存不涨 | 回退基线 |
| G7 | 消融是否支持因果？ | BRG > baseline；FS-Role > BRG；HUMAN-YIELD > 无让位（human 轴）；角色提示 > 通用提示 | 保留有效部分，砍掉无效部分 |
| G8 | 正式提交是否值得？ | 配对 A/B + bootstrap：总平均 ≥+2pp；95% CI 下界 > −1pp；至少 3/5 单任务方向为正 | 不烧正式提交 |

**统计现实**：320 trials，若 p≈0.3，总平均 SE≈2.5pp；单任务 10 trials 的 SE≈14.5pp。**单任务 +10pp 都可能只是噪声**。所以：

- 单任务只做“粗筛”，不要用单任务 10 次的结果宣布胜利；
- 用配对任务/配对 trial、bootstrap、分层分析（双臂高/低、接触 H/M/L、human 轴）；
- 正式提交前至少重复一次关键 A/B，避免被预览榜单的合成噪声带偏。

总分只用于排序，不能把 I1–I10 简单相加（角色/脚本/让位/伺服在 trial 上重叠）。

**为什么 I1/I2/I3 是主押注**：

- 它们分别对应三个灵感词，且**互不替代**：I1 解决“两只手怎么分工”，I2 解决“新物体怎么套旧角色”，I3 解决“人来了怎么办”。
- 它们都**不新增学习模型**：I1 是 QP，I2 是检索，I3 是状态机；VLA 仍是唯一学习模型。
- 它们都能在**单任务通道**上快速证伪：I1 看相对位姿误差/接触成功率；I2 看 top-3 角色命中；I3 看脚本人手/物体移动的恢复率。
- 它们的失败模式清楚：I1 可能投影过强导致 VLA 动作被扭曲；I2 可能检索错脚本；I3 可能误让位导致超时。每个都有回退开关。

**为什么 I4–I10 是辅助**：

- I4 让 VLA “听懂角色提示”，但如果没有 I1 的投影，提示可能被忽略；如果 I1 没有 I4，VLA 可能输出与角色冲突的动作。两者互补。
- I5/I6/I7 是第 12 轮的执行层，继续保留；I5 是 I1/I3 的时间基础。
- I8 是跨机器人鲁棒性，成本低，但增益不确定；先做重投影检查，不通过就不投入。
- I9 降级为离线编辑检测/触发，不作为主学习模块。
- I10 是 I3 的子行为，先做“暂停/让位”，再做“交接”。

**为什么 I11–I18 剪枝**：

- 规则/接口/算力/延迟的硬约束，不是“效果不好”的问题；继续投入会浪费时间。
- 特别是第二 VLA/LLM：BiCICLe、Harness VLA 都证明有效[S25][S28]，但它们在 UniBot 的“同一模型”规则下有解释风险；我们不冒这个险。
- 深度网络/6D 位姿：腕部有内参、头部有双目，先用几何；不要引入第二模型。
- 完整世界模型：DreamZero 的 14B/2×GB200s 已经说明成本；我们做执行层，不做基座。

## 6. 与第 10–12 轮的关系：保留、升级、剪枝

**保留**：

- 第 10 轮 FACT-VLA 的相位化 BC、CAC 柔顺执行、EGP 证据门控；
- 第 11 轮 GEO-RESIDUAL 的动作条件化残差、米制表面距离、编辑检测；
- 第 12 轮 CHUNK-SERVO 的“30 步规划 + 5 步执行”、DG-KEYFRAME 相对目标、单任务通道策略；
- 官方 WLA 基座、33k 演示、官方 rubric、N 端口隔离。

**升级**：

- 单臂最后 3 厘米 → **双臂角色图**：不再只问“怎么插”，先问“谁扶、谁插、谁让”。
- 目标位姿检索 → **角色脚本检索**：不只检索“抓哪里”，还检索“这一阶段谁 LEAD/STABILIZE”。
- 人为干扰 → **HUMAN-YIELD**：从“检测异常后停”升级为“让位/护持/交接/重定位”。
- 固定 5 步 → **角色感知有效视野**：LEAD 短、STABILIZE 长、HANDOVER 最短。
- 手工相位 → **DTW 对齐脚本**：相位来自检索脚本的对齐，不是拍脑袋。

**剪枝**：

- 不做第二个学习模型/LLM 规划器/多 VLA；
- 不做逐任务策略；
- 不做从零训世界模型/6B；
- 不做深度估计网络/6D 位姿网络；
- 不做力/触觉/音频闭环；
- 不做完整 sim-to-real 策略训练；
- 不做 30Hz 广域网伺服；
- 不把预览榜单的任务排名当实测难度。

## 7. 风险与剪枝

| 风险 | 影响 | 缓解 |
|---|---|---|
| 角色分段错误 | 投影到错误角色，反而降成功率 | G0 人工抽检；置信度低回退 VLA；先只对 5 个任务启用 |
| 脚本检索 mismatch | 新物体/新背景检索错脚本 | top-3 重打分；角色冲突则不投影；任务级固定脚本兜底 |
| 投影过强 | VLA 的细动作被 QP 扭曲 | 软约束/权重可调；只在 STABILIZE/BOTH_CARRY 用；LEAD 保留 VLA |
| 让位误触发 | 超时/任务失败 | 有界等待；误触发率统计；只在 human 轴启用；可关 |
| 人手检测漏检 | 碰撞/不安全 | 不声称 100%；减速/限幅；腕部遮挡兜底；不确定时不交接 |
| 单模型解释 | 被判定为第二个模型 | C1/C2/C3；投影/状态机无学习权重；提交材料写清楚 |
| 远程 RTT 高 | 5 步执行也跟不上 | H=8；关投影；预测补偿；单任务通道测 p99 |
| 32 任务脚本库维护 | 工程量大 | 先 5 任务；自动分段 + 人工抽检；脚本 JSON 化 |
| 评测噪声 | +2pp 假阳性 | 配对 A/B、bootstrap、重复；320 trials SE≈2.5pp |
| 过拟合预览榜单 | 把合成任务排名当难度 | 只当先验；用单任务通道和真实 A/B 重排 |
| 交接掉落 | 物体损坏/失败 | 低速低高度；夹爪闭合度门控；先不做交接 |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |

## 8. 一句话押注

**用官方 WLA 做单模型双臂规划，用 33k 演示检索出的角色脚本做确定性投影，用让位状态机处理人为干扰——把“谁来做、谁稳住、谁让位”显式接进控制环。**

# 第 13 轮产物 · DUET 技术报告

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「DUET」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是把它们的执行层从“单臂最后 3 厘米”升级为“双臂角色 + 少样本记忆 + 人”。

## 0. 结论与边界

### 0.1 一句话结论

官方 WLA 的 30 步 chunk 解决了吞吐，但没有解决“两只手谁做什么、没见过的东西怎么套旧经验、人来了怎么办”；DUET 用同一个 WLA 输出双臂动作，用 33k 演示检索出的**角色脚本**做确定性投影，用**让位状态机**处理人为干扰，在不新增学习模型的前提下，把双臂协调、少样本泛化和人机安全同时接进控制环。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、排行榜 JSON 直接核实 | 规则、API、33,276 eps、WLA `chunk_size=30`、榜单 29.7% |
| B | 我们在公开数据/网页上做的分析，可复现 | 榜单 `step~success` 回归、跨模型任务相关、BI\*、双臂抽样指标 |
| C | 设计假设，需 G0–G8 验证 | BRG +6pp、FS-Role top-3≥80%、HUMAN-YIELD 恢复≥60% |

### 0.3 本轮不做什么

- 不从零训 VLA/World Model；官方 WLA 已开源 6B 基座。
- 不做完整 sim-to-real 策略训练；数字孪生只做控制器/状态机风洞。
- 不做第二个学习模型/LLM 规划器/多 VLA；BRG 是 QP，FS-Role 是检索，HUMAN-YIELD 是状态机。
- 不做 6D 物体位姿网络/深度估计网络；用腕部内参 + 头部双目 + 几何。
- 不做力/触觉/音频闭环；API 没有。
- 不把预览榜单的任务排名当实测难度；只当先验。
- 不做逐任务策略；规则要求通才单模型。
- 不做 30Hz 广域网视觉伺服；用 5 步 chunk/双频。
- 不把 ROS2 当提交接口；官方只认 `PolicyService` 的 Python 接口。

## 1. 事实核对

### 1.1 排行榜：8 个模型，29.7% 是预览分

2026-10-31 通过 `r.jina.ai` 抓取 `/leaderboard_data.json`，8 个模型均为 `is_multitask=true`[S3]：

| # | 模型 | 用户 | 平均成功率 | 平均步骤分 | 平均时长 |
|---:|---|---|---:|---:|---:|
| 1 | MolmoAct2 | DexHacker | **29.7%** | 39.0 | 44.02 s |
| 2 | WALL-OSS-0.5 | Generalist Robotics | 28.5% | 38.9 | 43.74 s |
| 3 | DreamZero | World Model Lab | 27.9% | 37.9 | 44.59 s |
| 4 | Spirit-v1.5 | VLAGO | 25.9% | 34.4 | 45.19 s |
| 5 | DM0 | Embodied AI Institute | 23.5% | 31.7 | 45.11 s |
| 6 | PI-0.5 | RoboReasoner | 22.8% | 30.6 | 43.88 s |
| 7 | GigaBrain-0 | xembody | 22.6% | 29.5 | 43.76 s |
| 8 | GR00T N1.5 | Humanoid Dynamics | 20.5% | 28.1 | 44.71 s |

**预览证据（可复现）**：

1. **生成来源**：JSON 顶层 `"generated_from": "gen_leaderboard.py"`；这不是评测日志，是生成脚本[S3]。
2. **视频占位**：MolmoAct2、WALL-OSS-0.5、DreamZero、GigaBrain-0 的详情页，32 个任务全部显示“测试视频占位，后续可替换为真实视频文件”[S4]。
3. **统计指纹**：
   - 每个模型的 `avg_step_score` 与 `avg_success_rate` 线性拟合 **R²=1.000000（8/8）**，整体 R²=0.9955；
   - 成功率出现 6.3、9.03、11.33、42.0 等值，不是 10 次试验的 0/10、1/10…；
   - 把 8 个模型当变量、32 个任务当样本，模型间任务成功率平均相关仅 **0.098**（8×8 相关矩阵的非对角均值）；
   - 跨模型任务成功率的标准差均值约 5.6pp，但模型间相关很低，说明“任务画像”不像同一套真实评测。

**结论**：榜单可当“哪些方向有人做、大致什么量级”的先验；不能把某任务 9% 当真实难度，也不能把 29.7% 当不可超越的 SOTA。正式决策必须用单任务通道和配对 A/B 重排。

### 1.2 比赛规则（A）

官方参赛手册（飞书 docx，2026-10-31 通过 `r.jina.ai` 抓取；稳定拿到 §1.1–§2.2，后续章节可能截断，最终以官方页面为准）核实[S6][S7]；端口约定来自提交 README[S9]：

| 项 | 规则 |
|---|---|
| 模型 | **所有任务须基于同一模型完成，不得混合多个模型一起测试**；模型类型不限（World Model、VLA 均可） |
| 任务 | 32 项桌面任务；抓取、放置、双手协作是核心能力 |
| 次数 | 每任务 **10 次独立运行** |
| 泛化 | 5 类各 2 次：位置、干扰物、桌面背景、未见物品、**人为干扰** |
| 人为干扰 | 规则举例是“临时改变物品位置等”，不一定出现人手；考察鲁棒性与抗干扰能力 |
| 时限 | 单次真机执行上限 **180 s** |
| 排名 | 先比 32 任务总平均成功率；相同看总平均步骤分；再相同看**更早提交** |
| 部署 | 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态隔离 |
| 测试通道 | 另有**不计分的单任务测试通道**，可测单任务成功率/步骤分 |

**对方案的约束**：

- 不能用一个 LLM 做高层规划、再用一个 VLA 做执行；这有“混合多个模型”的解释风险。
- 不能为每个任务训一个策略；规则要求通才单模型。
- 必须每端口独立、CPU 轻量、GPU 可共享；不能假设只有一台机器人。
- 单任务通道是唯一安全的 A/B 场地；正式提交前不要把 320 trials 浪费在未过门的模块上。

### 1.3 提交 API（A）

提交模板 README（2026-10-31 复核）给出[S9]：

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640** |
| 本体 | 双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str` |
| 动作空间 | `control_space` 仅 `"joint"` 或 `"ee"`，二者互斥 |
| EE 动作 | 左/右 `ee_pose_gripper_base [6]`（绝对目标位姿，xyz+rpy，base 系） |
| 共享动作 | 左/右 `gripper [1]`、`pivot [7]` |
| chunk | `action_chunk_size` 在 metadata 中固定，≥1；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action` |
| token | `metadata.token` 握手校验一次；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile、audio** |
| 监控 | 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分 |

**关键推论**：

- 若 `action_chunk_size=30`、控制 30Hz，一次 `get_action` 后有 **1 秒开环**；chunk 内没有新观测，也没有打断机制。视觉伺服/让位要生效，必须把 metadata 的 chunk 降到 3–8 步，或接受 1 秒的“盲区”。
- 四路 RGB 足够做 2D 视觉伺服、头部双目深度、腕部局部对齐；不够做力控/触觉闭环。
- `action_chunk_size` 是 metadata 固定值，不能假设可以在一次 episode 内动态改；本报告默认 **H=5**，用单任务通道验证 H=5 vs H=8。
- `pivot [7]` 的语义必须先用 `example_client.py`/单任务通道验证；若不确定，回退全零 pivot，避免动作被拒。

#### 1.4.1 腕部内参修正（重要）

第 12 轮产物写“腕部相机没有内参矩阵”，这是错的。32 个数据集的 `camera_params.wrist_left.color.camera_matrix` 与 `wrist_right.color.camera_matrix` 都在；HangCup 示例：

```text
wrist_left.color  = [436.4058, 0, 323.9217; 0, 435.9215, 242.9332; 0, 0, 1]
wrist_right.color = [435.1151, 0, 319.0249; 0, 434.4995, 240.9933; 0, 0, 1]
head_stereo       = fx≈282, baseline 58.2526 mm, rectified=true
wrist ir1/ir2     = 640×480, baseline≈18 mm, extrinsics_to_color 也在
```

含义：

- 腕部 2D 伺服不需要“一次性棋盘格标定”才能开始；可以直接用数据集内参加畸变校正。
- 头部双目仍可用于 0.5–1.0 m 的局部深度；0.5–1.0 m 上视差约 16–33 px，足够局部毫米级深度。
- 线上 API 不给 `camera_info`，但数据集内参可作为先验；跨机器人若相机型号一致，误差主要来自装配，需一次重投影检查。
- 腕部 IR 立体（18 mm 基线）在离线数据里可用于近距深度；线上只有 RGB，不能依赖。

#### 1.4.3 BI\* 定义与稳健性

```text
s_L, s_R = 左/右 EE 位置三轴标准差的均值
g_L, g_R = 左/右夹爪动作标准差
bal      = 2·min(s_L,s_R)/(s_L+s_R)
gbal     = 2·min(g_L,g_R)/(g_L+g_R)
BI*      = 1000 · min(s_L,s_R) · bal · gbal
```

解释：

- `min(s_L,s_R)` 惩罚“只有一只手在动”的伪双臂任务；
- `bal` 惩罚左右动作量严重不对称；
- `gbal` 惩罚“一只手一直夹住、另一只手完全不夹”的单手主导；
- 乘 1000 只是把数值放到 0–100 的可读范围。

稳健性：与上一轮 BI 的 Spearman ρ≈0.78；高分组在两种算法下都包含 ArrangePlates、FoldTowel、StorePaddle、OrganizeBookshelf、OrganizeTools；低分组都包含 HangCup、SpellRobot、PickOutBatteries。它不是官方指标，只用于分层和实验排序。

**共同瓶颈**（不是“模型不够大”）：

1. **开环 chunk**：MolmoAct2 自己承认整批执行不重规划；UniBot 的 chunk 内也没有新观测。接触误差在 1 秒内无人纠正[S16][S9]。
2. **双臂角色未显式化**：21D 动作把两只手当联合向量；没有“谁 LEAD、谁 STABILIZE、何时交换”的结构。接触时两只手都可能漂。
3. **少样本记忆未进入控制**：33k 演示主要被当成 BC 训练集；没有被当成“角色脚本库”在测试时检索。
4. **人未被建模**：人为干扰是 20% 的 trials，但多数策略把人的进入当成视觉噪声或直接超时；没有让位/护持/交接的社会行为。
5. **世界模型不解决接触**：视频预测可以告诉你“杯子应该挂上去”，但不能保证 2 mm 的孔位对齐；最后 3 厘米仍是控制问题。

## 2. 问题形式化

### 2.1 符号

- `o_t = {I_t^1..4, q_t, u_t, l}`：四路 RGB、本体、语言。
- `x_t = (x_t^L, x_t^R) ∈ SE(3)^2`：左右 EE 位姿。
- `g_t = (g_t^L, g_t^R) ∈ {0,1}^2`：夹爪开合。
- `A_t = {a_{t+i}}_{i=0}^{H-1}`，`a = (a^L, a^R)`：VLA 输出的 H 步双臂动作；WLA 内部可输出 30 步，执行层取前 H 步。
- `σ = (task, phase, r_L, r_R, g_L^*, g_R^*, T_{LR}^*, w_L^*, w_R^*, τ)`：角色脚本。
- `r ∈ R = {LEAD, STABILIZE, BOTH_CARRY, HANDOVER, IDLE}`。
- `h_t ∈ {MONITOR, SLOW, YIELD, HANDOVER, RELOCALIZE, RESUME}`：人/环境监督状态。

### 2.2 目标

最大化 32 任务总平均成功率，满足：

```text
max_π  E[ Σ_t success_t ]
s.t.    π 只包含一个学习模型（WLA）
        π 的其余部分是可解释的确定性控制器/检索/状态机
        动作满足 joint/velocity/workspace/self-collision 约束
        人为干扰下不发生碰撞；让位有界，不无限等待
```

### 2.3 角色投影

给定 VLA 原始 chunk `A_t` 和检索脚本 `σ*`，执行层输出：

```text
A_t^* = Π_{C(σ*)}( A_t )
```

其中 `C(σ*)` 是角色约束集：

- `STABILIZE`：`x^arm = w^*`（或保持当前位姿），`g^arm = g^*`；
- `LEAD`：`a^arm = a^{VLA,arm}`，只做限速/限幅；
- `BOTH_CARRY`：`T_L^{-1} T_R = T_{LR}^*`；
- `HANDOVER`：夹爪时序 + 交接位姿；
- `IDLE`：`x^arm = x^{safe}`。

### 2.4 检索目标

```text
σ* = argmax_{σ ∈ Library} score(q_t, σ)
score = w1·task_match + w2·phase_match + w3·object_sim
      + w4·pose_sim + w5·role_prior_match
```

若 `score(top1) - score(top2) < δ` 且 `role(top1) ≠ role(top2)`，不投影，回退 VLA。

### 2.5 人/环境监督

```text
h_{t+1} = F(h_t, o_t, x_t, g_t, σ*)
```

`F` 是确定性状态机，不是学习模型。`YIELD/HANDOVER/RELOCALIZE` 只在触发时覆盖 `A_t^*`。

### 2.6 角色感知 chunk

```text
H(r) = 3–5   if r ∈ {LEAD, HANDOVER}
       5–8   if r = BOTH_CARRY
       8–10  if r = STABILIZE
       10–15 if r = IDLE
```

metadata 的 `action_chunk_size` 固定为 `H_max=5`（或 8），执行层按角色截断/填充；不动态改 metadata。

## 3. 系统设计

### 3.1 进程拓扑（N 端口）

```text
             ┌─────────────────────────────┐
             │  Shared WLA model server    │
             │  6B, 24GB GPU, batched      │
             └─────────────┬───────────────┘
                           │ local IPC / HTTP
     ┌─────────────────────┼─────────────────────┐
     │                     │                     │
┌────▼─────┐         ┌─────▼────┐          ┌─────▼────┐
│ Port 8765│   ...   │ Port 8766│   ...    │ 8765+N-1 │
│ Policy   │         │ Policy   │          │ Policy   │
│ +BRG     │         │ +BRG     │          │ +BRG     │
│ +FS-Role │         │ +FS-Role │          │ +FS-Role │
│ +YIELD   │         │ +YIELD   │          │ +YIELD   │
└──────────┘         └──────────┘          └──────────┘
```

- 每个端口一个轻量进程，独立 `reset()`/状态机/脚本缓存；共享 GPU 模型服务器做批处理。
- 若 N 很小（1–3），也可以每端口独立加载模型；但 6B × N 的显存要算清楚。
- CPU 侧：DTW/检索/QP/状态机，单端口 <1 核；N 端口并行也够。
- 网络：evaluator 连接每端口，token 每次 `get_action` 校验；不要让一个端口阻塞其他端口。

### 3.2 离线流水线

### 3.3 在线循环

```text
reset():
  clear episode state, script cache, human state, retry count

get_action(obs):
  state.update(obs)
  if state.human_state in {YIELD, HANDOVER, RELOCALIZE}:
      return human_supervisor_chunk(obs, state)

  q = query(obs, state)
  scripts = retrieve(q, topk=3)
  σ = choose_script(scripts, state)

  if σ is None or σ.confidence < δ:
      A = wla(obs)                      # 回退：不投影
  else:
      A = wla(obs, role_hint=σ.hint)    # 同一 VLA，语言条件
      A = project(A, σ, obs)            # BRG 确定性投影

  A = safety_clip(A, obs)
  A = human_supervisor(A, obs, state)
  return A[:H]
```

### 3.5 伪代码（完整）

```python
def get_action(self, obs):
    self.state.update(obs)

    # 1) 人/环境监督优先
    h = self.human_monitor.update(obs, self.state)
    if h in ("YIELD", "HANDOVER", "RELOCALIZE"):
        return self.human_monitor.chunk(obs, self.state)

    # 2) 检索角色脚本
    q = self.make_query(obs, self.state)
    cands = self.library.retrieve(q, topk=3)
    script, conf = self.choose_script(cands, self.state)

    # 3) 同一 WLA；角色提示是语言条件，不是第二个模型
    if script is None or conf < self.delta:
        A = self.wla.infer(obs)                   # fallback
    else:
        A = self.wla.infer(obs, role_hint=script.hint)
        A = self.brg.project(A, script, obs)      # QP/虚拟夹具

    # 4) 安全投影 + 角色感知 chunk
    A = self.safety.clip(A, obs)
    H = self.scheduler.horizon(script.role_L, script.role_R)
    return A[:H]
```

## 4. 算法细节

### 4.1 角色分段

对每条演示，构造信号：

```text
z_t = [x_t^L (3), x_t^R (3), g_t^L, g_t^R, ||v_t^L||, ||v_t^R||]
```

分段规则（先规则，后人工抽检）：

1. **抓取段**：某夹爪从 open→close，且 EE 速度在闭合后 0.2 s 内下降 >50%。
2. **搬运段**：两 EE 速度都 > 阈值，且夹爪保持闭合。
3. **支撑段**：一臂 EE 速度 < 阈值持续 >0.5 s，另一臂在动；支撑臂夹爪闭合。
4. **插入/操作段**：LEAD 臂速度低、接近方向稳定，STABILIZE 臂几乎静止。
5. **交接段**：两夹爪在 0.5 s 内一开一闭，且 EE 距离 < 阈值。
6. **释放/退臂段**：夹爪 open，EE 远离物体。

对 5 个任务（PlugInEthernet、FoldTowel、ZipUp、PackBag、Unlock）人工标注 20 条，计算自动分段与人工角色一致率；≥85% 才扩到 32 任务，否则只用手工 5 任务。

### 4.2 角色推断：DTW 对齐

在线不需要“阶段分类器”；用检索脚本的 DTW 对齐：

```text
query prefix: z_{t-T+1:t}
script exemplar: z^σ_{1:K}
cost(i,j) = ||z_i - z^σ_j||^2
D(i,j) = cost(i,j) + min(D(i-1,j), D(i,j-1), D(i-1,j-1))
phase = argmin_j D(T,j)
confidence = margin between best and second-best script
```

工程优化：

- 先用 task ID 过滤到 3–6 条脚本，再做 DTW；
- 下采样到 10 Hz、Sakoe-Chiba band 限制；
- 只在阶段切换附近跑 DTW，其他时候用夹爪/速度规则；
- 单端口 CPU 预算 <10 ms。

### 4.3 BRG 投影

#### STABILIZE

```text
e = w* - x_t
a = clip(Kp e - Kd v_t, v_max)
```

若 `w*` 不可用：`a = 0`（保持当前位姿），只允许小角度柔顺。夹爪按 `g*`。

#### LEAD

```text
a = clip(a^VLA, v_max, workspace)
```

不做强投影，避免扭曲 VLA 的细动作；只做安全限幅。

#### BOTH_CARRY

设当前相对位姿 `T_rel = T_L^{-1} T_R`，目标 `T*`。误差：

```text
e = log( T* · T_rel^{-1} ) ∈ se(3)
```

线性化 `T_L(a_L)`、`T_R(a_R)`，得到 `J_L δ_L - J_R δ_R = -e`。解 QP：

```text
min_{δ_L,δ_R}  ||δ_L - δ_L^VLA||²_WL + ||δ_R - δ_R^VLA||²_WR
s.t.           J_L δ_L - J_R δ_R = -e
               δ_min ≤ δ ≤ δ_max
```

若 QP 不可行，降级为“虚拟夹具”：把 `-e` 均分给两臂，各自做位置修正；再不可行就回退 VLA。

#### HANDOVER

```text
phase 1: g_stabilize ← close, g_lead ← open
phase 2: both → handover pose (脚本)
phase 3: g_stabilize ← open, g_lead ← close
phase 4: swap roles
```

每一步有超时/夹爪闭合度门控；失败则回退“轻放—重抓”。

#### IDLE

安全收臂：离开工作区、避免遮挡相机、离桌面 > 5 cm；不参与 VLA 联合动作。

### 4.4 FS-Role 检索

**查询特征**：

- `task`：语言已知，one-hot/字符串匹配；
- `phase`：DTW 估计；
- `object_sim`：bbox 尺寸/长宽比 + HSV 直方图 + 初始位姿；
- `pose_sim`：当前 EE 相对物体/支撑面的位姿；
- `role_prior_match`：当前角色与脚本角色的一致性。

**打分**：

```text
score = 0.35·task_match + 0.25·phase_match + 0.15·object_sim
      + 0.15·pose_sim + 0.10·role_prior_match
```

权重先用先验，单任务通道上调；不要用预览榜单拟合。

**回退**：

- top-1 置信度 < δ：不投影，VLA 原始动作；
- top-1/top-2 角色冲突：不投影；
- 检索到的 `T_LR*` 与当前相对位姿差 > 10 cm/30°：视为 mismatch，不投影；
- 连续 3 次 mismatch：降级到任务级固定脚本。

**少样本泛化**：

- 角色脚本与物体外观解耦；“先扶住—再对齐—再插入—再释放”不依赖具体物体。
- 新物体只影响 `object_sim` 和抓取点；用几何/颜色检索，不用 6D 位姿网络。
- 若新物体与所有脚本都不相似，回退 VLA；不强行投影。

### 4.5 HUMAN-YIELD

#### 检测

| 信号 | 方法 | 触发 |
|---|---|---|
| 工作区运动 | 头部右高/双目帧差，降采样，机器人自身 EE/臂投影遮罩 | 大块新运动进入工作区 |
| 腕部遮挡 | 腕部图像方差/熵突降，或近景大块肤色/纹理 | 人手/物体突然靠近 |
| 物体位移 | 脚本预期物体位置 vs 当前颜色/bbox | 物体被挪走/挪偏 |
| 跟踪误差 | `‖x_t - x_{t-1} - a_{t-1}‖` 突增 | 外部阻挡/碰撞 |
| 夹爪异常 | 夹爪闭合度与脚本不符 | 抓空/被拿走 |

**限制**：不做人脸识别、不录音、不保存身份；视觉处理本地；检测不到人不等于安全。

#### 状态机

```text
MONITOR ──human_near──▶ SLOW ──human_in_workspace──▶ YIELD
   ▲                       │                           │
   │                       │ human_leaves              │ human_reaches
   │                       ▼                           ▼
   └──── RESUME ◀──── RELOCALIZE ◀──── object_moved   HANDOVER
```

| 状态 | 行为 | 退出 |
|---|---|---|
| `MONITOR` | 正常执行 | 触发 |
| `SLOW` | 速度 50%，保持夹持 | 人离开/进入 |
| `YIELD` | 暂停 LEAD；STABILIZE 保持/轻放；收臂 3–5 cm | 人离开/物体稳定 |
| `HANDOVER` | 张开夹爪，递到人可拿位姿；低速低高度 | 人接管/离开 |
| `RELOCALIZE` | 重新观察，重检索脚本，CHUNK-SERVO 对齐 | 对齐成功 |
| `RESUME` | 从当前状态重规划；必要时重抓 | 回到 MONITOR |

**有界等待**：`YIELD/HANDOVER` 最多 3 s；超时后轻放物体，转 `RELOCALIZE`；不无限等待。

**社会影响**：

- 正面：减少碰撞、提高共享工作台可接受度；让位/交接比“停在原地”更可读；少样本角色记忆降低数据成本。
- 负面：误让位→超时；误交接→掉落；过度信任；遮挡/光照漏检。
- 缓解：有界等待、低速交接、失败回退、单任务通道统计误触发率；提交材料明确“不是安全认证”。

### 4.6 角色感知 chunk 调度

| 角色 | H | 理由 |
|---|---:|---|
| LEAD 接近/插入 | 3–5 | 接触误差累积最快 |
| STABILIZE 保持 | 8–10 | 目标变化慢，省 RTT |
| BOTH_CARRY | 5–8 | 相对位姿要同步 |
| HANDOVER | 3–5 | 夹爪时序不能错 |
| IDLE | 10–15 | 不需要频繁调用 |

实现：

- metadata `action_chunk_size = 5`（安全值）；
- WLA 内部仍输出 30 步；执行层取前 `H` 步；
- 若 `H > 5`，用 hold/零速度填充到 5 步？这会浪费；更好的做法是把 metadata 设为 5，所有角色最多执行 5 步；`STABILIZE/IDLE` 的“省 RTT”用“每 5 步调用一次但动作只做微调”实现，而不是改 chunk。
- 若单任务通道证明 evaluator 接受可变长度/截断，再考虑 `H=8`；否则固定 5。

### 4.7 失败处理

| 失败 | 检测 | 处理 |
|---|---|---|
| 抓空 | 夹爪闭合度/物体未随动 | 重抓（最多 2 次）；换抓取点 |
| 插入卡住 | LEAD 速度低、跟踪误差大、视觉无进展 | 回退 1–2 cm，微调姿态，重试 |
| 支撑滑移 | STABILIZE 位置漂移 > 阈值 | 重新夹紧/换支撑点 |
| 检索 mismatch | top-1 置信度低/角色冲突 | 回退 VLA；任务级脚本 |
| 人/物变化 | HUMAN-YIELD | 让位/重定位/恢复 |
| 超时 | 180 s | 提前 10 s 进入安全收尾；不要硬撞 |

### 5.4 人/环境干扰测试

- 脚本人手进入：从左侧/右侧/上方，速度 0.2/0.5 m/s；测检测延迟、让位距离、碰撞。
- 脚本物体挪动：任务中途把物体平移 5/10/20 cm；测重定位/恢复。
- 脚本交接：人伸手向机器人持有的物体；测交接成功率/掉落。
- 通过标准：G4；不通过只做减速/暂停，不做交接。

### 5.5 全量干跑

- 32 任务 × 10 trials，N 端口；先 dry-run（不正式提交）验证：
  - 端口隔离/reset 干净；
  - 内存不涨、GPU 批处理稳定；
  - p99 延迟/超时率；
  - 脚本库加载时间。
- 通过标准：G6；不过不提交。

### 5.6 统计

- 320 trials；若 p≈0.3，总平均 SE≈2.5pp；单任务 10 trials SE≈14.5pp。
- 单任务只做粗筛；正式决策用：
  - 配对任务/配对 trial；
  - bootstrap 95% CI；
  - 分层：双臂高/低、接触 H/M/L、human 轴；
  - 至少重复一次关键 A/B。
- 不要用预览榜单的任务排名做 early stopping；它是合成/占位数据。

### 6.3 主押注展开

#### I1 BRG：为什么 +6pp 是合理的

- 受影响：12 个双臂/接触密集任务（BI\* 高或最后接触为 H，约 37.5%）；这些任务的接触/相对位姿对角色最敏感。
- 失败模式：VLA 在接触时两只手都漂；STABILIZE 没有真正保持；BOTH_CARRY 相对位姿漂移。BUDS 的角色分解在 4 个真实任务上比非结构化稳定臂高 56.0%[S24]，说明“角色”不是玄学。
- 成本：3 人周（QP/虚拟夹具 + 5 任务调参 + 仿真）。
- 风险：投影过强扭曲 VLA；用软约束/回退。若 G3 不过，砍掉 BOTH_CARRY，只保留 STABILIZE。

#### I2 FS-Role：为什么 +4pp 是合理的

- 受影响：未见物品/背景/位置/干扰物 4 类 = 8/10 trials；但角色脚本主要帮“未见物品/背景”，保守取 50% 的 trials。
- 失败模式：新物体外观变化导致 VLA 抓取点错；但“先扶—再插—再放”的角色不变。BUDS 用 20 个演示在类内新物体上 52.7%[S24]；VLBiMan/YOTO++ 用单个人类演示做 one-shot 泛化[S26][S27]；说明少样本角色先验有空间。
- 成本：3 人周（分段 + 脚本库 + 检索）。
- 风险：检索错脚本；用置信度/角色冲突回退。

#### I3 HUMAN-YIELD：为什么 +10pp 是合理的

- 受影响：human 轴 2/10 = 20%；baseline 在人为干扰下可能直接失败/超时；让位/重定位若能把一半失败转成功，就是 +10pp on that axis，总分 +2pp。
- 失败模式：人把物体挪走，VLA 继续执行旧 chunk；或人伸手，机器人继续撞。HUMAN-YIELD 先暂停/重观察/重定位，再恢复。
- 成本：2 人周（检测 + 状态机 + 仿真）。
- 风险：误触发/漏检；有界等待、低速、回退；先只做暂停/重定位，不做交接。

### 6.4 保留/升级/剪枝

**保留**：

- 第 10 轮 FACT-VLA 的相位化 BC、CAC 柔顺执行、EGP 证据门控；
- 第 11 轮 GEO-RESIDUAL 的动作条件化残差、米制表面距离、编辑检测；
- 第 12 轮 CHUNK-SERVO 的“30 步规划 + 5 步执行”、DG-KEYFRAME 相对目标、单任务通道策略；
- 官方 WLA 基座、33k 演示、官方 rubric、N 端口隔离。

**升级**：

- 单臂最后 3 厘米 → **双臂角色图**：不再只问“怎么插”，先问“谁扶、谁插、谁让”。
- 目标位姿检索 → **角色脚本检索**：不只检索“抓哪里”，还检索“这一阶段谁 LEAD/STABILIZE”。
- 人为干扰 → **HUMAN-YIELD**：从“检测异常后停”升级为“让位/护持/交接/重定位”。
- 固定 5 步 → **角色感知有效视野**：LEAD 短、STABILIZE 长、HANDOVER 最短。
- 手工相位 → **DTW 对齐脚本**：相位来自检索脚本的对齐，不是拍脑袋。

**剪枝**：

- 不做第二个学习模型/LLM 规划器/多 VLA；
- 不做逐任务策略；
- 不做从零训世界模型/6B；
- 不做深度估计网络/6D 位姿网络；
- 不做力/触觉/音频闭环；
- 不做完整 sim-to-real 策略训练；
- 不做 30Hz 广域网伺服；
- 不把预览榜单的任务排名当实测难度。

### 7.3 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 角色分段错误 | 投影到错误角色，反而降成功率 | G0 人工抽检；置信度低回退 VLA；先只对 5 个任务启用 |
| 脚本检索 mismatch | 新物体/新背景检索错脚本 | top-3 重打分；角色冲突则不投影；任务级固定脚本兜底 |
| 投影过强 | VLA 的细动作被 QP 扭曲 | 软约束/权重可调；只在 STABILIZE/BOTH_CARRY 用；LEAD 保留 VLA |
| 让位误触发 | 超时/任务失败 | 有界等待；误触发率统计；只在 human 轴启用；可关 |
| 人手检测漏检 | 碰撞/不安全 | 不声称 100%；减速/限幅；腕部遮挡兜底；不确定不交接 |
| 单模型解释 | 被判定为第二个模型 | C1/C2/C3；投影/状态机无学习权重；提交材料写清楚 |
| 远程 RTT 高 | 5 步执行也跟不上 | H=8；关投影；预测补偿；单任务通道测 p99 |
| 32 任务脚本库维护 | 工程量大 | 先 5 任务；自动分段 + 人工抽检；脚本 JSON 化 |
| 评测噪声 | +2pp 假阳性 | 配对 A/B、bootstrap、重复；320 trials SE≈2.5pp |
| 过拟合预览榜单 | 把合成任务排名当难度 | 只当先验；用单任务通道和真实 A/B 重排 |
| 交接掉落 | 物体损坏/失败 | 低速低高度；夹爪闭合度门控；先不做交接 |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |
| `pivot` 语义不一致 | 动作被拒/机器人不动 | 先用 `example_client.py`/单任务通道验证；保留零 pivot 回退 |
| 提交次数限制 | 无法多次 A/B | 邮件确认；单任务通道先验证；一次提交则保守 |

### 7.4 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 角色标签/脚本只离线生成；线上只有 VLA | 最低 | 保守首选 |
| C2 确定性控制器 | BRG 投影/让位状态机无学习权重；VLA 是唯一学习模型 | 低；需向官方说明 | 主推 |
| C3 同 checkpoint 特征 | 物体描述子用 VLA 同一 checkpoint 的 encoder，不加载第二个模型 | 低–中；需说明 | 需要强描述子时用 |

**禁止**：第二个学习策略、LLM 规划器、独立视觉编码器做在线决策、TwinVLA/VLA-Fabric 式多 VLA[S30][S31]、SocialVLA 式独立感知网关。它们可能更强，但在“同一模型”规则下有解释风险。
