## 1. 直觉与动机（三个灵感的碰撞）

**灵感 1（痛点分析 → 先把「痛」换算成分数导数，再决定投谁）**
直觉：前两轮的痛点清单是定性的，但比赛只有一个客观目标函数：成功率（主）+ 步骤分（tie-break）+ 180s 截止。一个痛点值不值得做，不取决于它听起来多痛，而取决于「修好它，期望分数涨多少 / 花多少成本」。按这个标准，最被低估的痛点不是泛化，而是**时间与轨迹**：32 个任务里有大量多物体任务，每个物体都是一个得分点；180s 内少做一个物体，成功率和步骤分同时掉。反过来，接触段的 1cm 过冲可能让整个任务失败——它属于成功率痛点，优先级高于任何 tie-break 优化。核心反直觉点：**痛点分析不是列清单，而是给每个痛点算「分数导数」；没有可观测签名的痛点只是假设，不配进账本。**

**灵感 2（轨迹优化 → VLA 输出的是路点，不是带时间的轨迹；时间与平滑度是免费的优化变量）**
直觉：策略输出一个 chunk 的位置目标，评测端按序执行；这等于把「路径」和「时间参数化」解耦了。BC 学到的轨迹通常有三类浪费：(a) 人手的抖动与异常段；(b) 自由空间按接触段的速度走，慢；(c) 每个 chunk 独立预测，接缝处速度不连续。经典轨迹优化正好补这三刀：约束平滑（min-jerk/加速度限）、路径-速度分解（TOPP，自由空间快、接触段慢）、滚动时域 C1 接缝。它不需要新数据、不需要改权重、不需要再训练，只花 CPU 毫秒。核心反直觉点：**在模型结构已经卷不动的时候，轨迹层是最后一块「不用训练就能拿分」的地方；但它的收益上限由低层控制器决定，必须先标定。**

**灵感 3（与第 2 轮数据引擎的合流 → 轨迹层是地板，数据引擎是天花板）**
直觉：第 2 轮把胜负手押在数据引擎（I1/I2/I5），方向没错，但数据引擎的成本高、周期长、负迁移风险大。痛点账本显示：I10/I11 这类轨迹层干预成本极低、风险可控，应该先做，作为「地板」；数据引擎继续做「天花板」。两者不冲突：轨迹级清洗（去抖、时间重采样、接触段降速）本身就是数据引擎的前处理，I5 的失败示教也可以用轨迹变形而不是图像扰动来造。核心反直觉点：**轨迹优化不只是推理期技巧，它还是数据引擎的「质检工位」；同一套轨迹表示，训练期和推理期各用一次。**

**三者统一**：痛点分析回答「先修哪个」，轨迹优化回答「用最低成本修执行层」，数据引擎回答「怎么把上限抬高」。本轮结论：**先用痛点账本把 I10/I11 排到队首，把轨迹层做成免费的 Pareto 改进；再把省下的预算投给 I1/I2/I5 的数据引擎。**

## 2. 严谨定义（先直觉，后形式化）

### 2.1 痛点与分数导数

**直觉**：痛点是「机制 → 可观测签名 → 分数变化」的三元组；不能观测的痛点是玄学，不能换算分数的痛点是审美。

**定义**：一个痛点 \(p=(m,o,A,\Delta S,\Delta T,C,\kappa)\)，其中 \(m\) 是机制，\(o\) 是离线可观测签名，\(A\) 是受影响的任务/运行集合，\(\Delta S\) 是修复后的期望成功率增量，\(\Delta T\) 是期望步骤分增量，\(C\) 是成本（GPU-hour/人周/真机 slot），\(\kappa\) 是置信度。分数杠杆：
\[
L_S(p)=\frac{\Delta S(p)}{C(p)},\qquad L_T(p)=\frac{\Delta T(p)}{C(p)}.
\]
排序规则：先按 \(L_S\) 降序（成功率先行），再按 \(L_T\) 降序（tie-break）；同时保留 \((\Delta S,\Delta T,C)\) 的 Pareto 前沿。\(\Delta S,\Delta T\) 的估计分三级：观察性回归（日志签名 → 分数）、反事实回放（离线把该痛点修掉/注入）、干预消融（L1/L2 真机）。**只有至少一级证据的痛点才进账本主体；其余进「待验证」区。**

### 2.2 分数-时间推导（为什么轨迹时间值钱）

**直觉**：步骤分是「在 180s 前完成了哪些里程碑」的加权计数；时间不是背景变量，是直接进分数的自变量。

**定义**：任务 \(t\) 的里程碑 \(k=1..K_t\)，权重 \(w_{t,k}\ge 0\)，\(\sum_k w_{t,k}=100\)。一次运行的步骤分
\[
\tau_{t,r}=\sum_{k=1}^{K_t} w_{t,k}\,\mathbf{1}[\text{milestone }k\text{ achieved by }D],
\]
\(D=180s\)。设里程碑完成时间为 \(T_{t,r,k}\)，则
\[
\tau_{t,r}=\sum_k w_{t,k}\,\mathbf{1}[T_{t,r,k}\le D].
\]
对轨迹做时间缩放 \(T_{t,r,k}\mapsto \rho T_{t,r,k}\)（\(\rho<1\) 为加速），步骤分增量为
\[
\Delta \tau_{t,r}=\sum_k w_{t,k}\left(\mathbf{1}[\rho T_{t,r,k}\le D]-\mathbf{1}[T_{t,r,k}\le D]\right).
\]
只有「原本卡在 \(D\) 附近」的里程碑对时间敏感；远离截止的里程碑加速不增分。这给出两条设计律：(a) **截止期感知**：优先压缩靠近 \(D\) 的高权重里程碑；(b) **不要全局均匀加速**：在远离截止的阶段加速只增加风险，不增分。

### 2.3 轨迹优化的形式化

**直觉**：把 chunk 当路点，求一条「贴合路点、满足速度/加速度/加加速度约束、接缝 C1、相位变速」的轨迹。

**定义**：给定路点 \(x_0..x_{T_a-1}\)、上一 chunk 的终端状态 \((q_0,\dot q_0)\)、相位 \(\phi(t)\in\{\text{free},\text{pre-contact},\text{contact},\text{transport},\text{release}\}\)，求 \(q(t),t\in[0,T_a\Delta t]\)：
\[
\min_{q}\; \int_0^{T_a\Delta t}\left(w_a\|\ddot q\|^2+w_j\|\dddot q\|^2\right)dt+\lambda\sum_i\|q(t_i)-x_i\|^2+\mu T
\]
s.t.
\[
q(0)=q_0,\ \dot q(0)=\dot q_0,\quad |\dot q|\le v_{\max}(\phi),\ |\ddot q|\le a_{\max},\ |\dddot q|\le j_{\max},
\]
joint limits / workspace. \(v_{\max}(\phi)\) 是相位相关速度帽：free 高、pre-contact 中、contact 低。求解用「B 样条路径 + 时间最优参数化（TOPP）+ 小 QP 接缝」三段式，避免在线解大规模 NLP。

**接缝度量**：第 \(k\) 与 \(k+1\) 个 chunk 的接缝跃变
\[
J_{\text{seam}}=\frac{\|\dot q_{k+1}(0)-\dot q_k(T_a\Delta t)\|}{\Delta t}.
\]
目标是把 \(J_{\text{seam}}\) 压到与 chunk 内加速度同量级，而不是追求零（零会牺牲响应）。

**截止期调度**：给定里程碑权重 \(w_k\)、预计时长 \(d_k\)、优先级约束，最大化 \(\mathbb E[\sum_k w_k\mathbf{1}[T_k\le D]]\)。独立里程碑用 Smith 规则（按 \(w_k/d_k\) 排序）作初值；有先后约束时用列表调度 + 小规模 DP；轨迹层通过压缩 \(d_k\) 改变可行域。

### 2.4 chunk 语义修正（对 I4 的硬约束）

**直觉**：`T_a` 是握手时固定的，评测端执行完整个 chunk 才回调用；所以「干预态短 chunk」不能靠临时改 `T_a` 实现，只能靠「chunk 内提前 hold」。

**定义**：固定 `T_a` 下，策略在干预态返回的 chunk 形如
\[
a_{0:m-1}=\text{stop/hold},\qquad a_{m:T_a-1}=q_{\text{current}},
\]
即用「提前 hold」模拟短 chunk；真正的反应延迟下界是 \(m\Delta t\)，而最坏反应延迟是 \(T_a\Delta t\)。因此 I4 必须同时标定「全局 `T_a`」与「chunk 内 hold 点」两个量，不能只写「自适应 chunk」。

## 5. 设计原则（新增 PR6–PR8，PR1–PR5 保留）

- **PR6 分数导数优先律**：任何投入先算 \(\Delta S/C\) 与 \(\Delta T/C\)；成功主导的痛点优先于 tie-break 主导的痛点；没有可观测签名的痛点不进主账本。
- **PR7 轨迹即分数律**：轨迹变换必须回答「它提高成功率，还是提高截止期内的里程碑吞吐」；平滑是手段不是目的；禁止自由空间/接触段用同一速度帽。
- **PR8 固定 chunk 律**：`T_a` 是全局超参；任何「自适应 chunk」必须落成「chunk 内 hold 点 + 全局 `T_a` 标定」，不能假设可以逐步改 `T_a`。
- PR1–PR5 保留（第 1/2 轮）。

## 3. I11 相位感知轨迹优化与截止期调度（新）★★★★★

### 3.1 直觉

VLA 输出的是**路点序列**，不是**带时间的轨迹**。评测端按序执行整个 chunk，因此「路径形状」「时间参数化」「接缝连续性」是三个可以独立优化的自由度。BC 数据里的人手抖动、自由空间慢速、chunk 接缝跳变，都可以在推理期用经典轨迹优化修掉，不需要重训。关键是**相位感知**：自由空间可以快，接触段必须慢；不能用一个全局速度。

### 3.2 形式化

给定路点 \(x_0..x_{T_a-1}\)、上一 chunk 终端状态 \((q_0,\dot q_0)\)、相位 \(\phi(t)\)，求 \(q(t)\)：
\[
\min_q \int_0^{T_a\Delta t}\left(w_a\|\ddot q\|^2+w_j\|\dddot q\|^2\right)dt+\lambda\sum_i\|q(t_i)-x_i\|^2+\mu T
\]
s.t. \(q(0)=q_0,\ \dot q(0)=\dot q_0,\ |\dot q|\le v_{\max}(\phi),\ |\ddot q|\le a_{\max},\ |\dddot q|\le j_{\max}\)，以及关节限位/工作空间。\(v_{\max}(\text{free})>v_{\max}(\text{pre-contact})>v_{\max}(\text{contact})\)。

接缝度量：
\[
J_{\text{seam}}=\frac{\|\dot q_{k+1}(0)-\dot q_k(T_a\Delta t)\|}{\Delta t}.
\]
目标是把 \(J_{\text{seam}}\) 压到与 chunk 内加速度同量级；不追求零，因为零会牺牲对干扰的响应。

截止期目标：
\[
\max\ \mathbb E\left[\sum_k w_k\mathbf{1}[T_k\le D]\right],\quad D=180s,
\]
其中 \(w_k\) 是里程碑权重、\(T_k\) 是完成时间。轨迹层通过压缩自由空间段的 \(d_k\) 扩大可行域；调度器决定先做哪个里程碑。

### 3.3 四个组件

1. **无触觉相位检测**：用 gripper 指令/状态、EE 速度、视觉关键点距离、动作幅值做阈值 + 滞回，输出 free / pre-contact / contact / transport / release。没有力/触觉（F8 前序事实），所以相位是**概率判断**，必须带置信度与回退：置信度低时用中性速度帽。
2. **约束平滑 + TOPP**：先对路点拟合三次 B 样条（软约束，保留路点保真度），再做路径-速度分解（TOPP）：沿路径 \(p(s)\) 求 \(s(t)\)，满足 \(|\dot p(s)|\dot s\le v_{\max}(\phi(s))\)、加速度/加加速度约束。离散成 M 段，解小 LP/QP；\(T_a\sim 8\)–16，规模很小，CPU 毫秒级。
3. **接缝 C1 滚动优化**：以 \(q_0,\dot q_0\) 为边界条件，解一个小 QP 调整 chunk 内部路点；硬约束 \(q(0)=q_0\)、\((q(1)-q_0)/\Delta t=\dot q_0\)，软约束贴合原路点。这样每个 chunk 的起点速度继承上一 chunk 的终点速度，消除接缝跳变。
4. **截止期里程碑调度**：估计每个里程碑的剩余时长 \(d_k\)，按 \(w_k/d_k\) 排序（独立里程碑的 Smith 规则初值），有先后约束时用列表调度 + 小 DP；若预计 \(>D\)，优先压缩高权重且靠近截止的 free 段，接触段不加速。

### 3.4 训练侧：轨迹清洗与增广（同一套表示，第二次使用）

- **去抖**：对示教动作做低通/样条平滑，但只平滑高频分量，保留接触段的慢速细节；用「平滑前后接触段成功率代理」做门禁，避免把关键接触动作平滑掉。
- **时间重采样**：把示教按弧长/相位重采样，生成不同执行速度的变体；这不是图像增广，而是**时间轴增广**，直接教策略「同一路径可以快/慢执行」。
- **接触段降速增广**：在 pre-contact/contact 段插入减速变体，教策略「接近接触时放慢」。
- **轨迹变形造失败示教**：把成功轨迹在接触点附近做横向/纵向偏移，生成「偏离→修正」段，替代一部分 I5 的图像扰动；用得分点检测器过滤。
- **质量加权**：把高频动作能量、离群段比例、平滑度作为 I2 的 per-episode 质量分，剪最差 10%。

### 3.5 与现有方案差异

| 方案 | 做什么 | 局限 |
|---|---|---|
| 直接 SFT / 加大模型 | 用更多数据/参数覆盖 | 不解决 chunk 接缝与时间非最优；成本高 |

### 3.6 可行性、资源、步骤、风险

- **可行性**：中-高。TOPP/QP 是成熟算法；\(T_a\sim 8\)–16，单次 QP 变量 <100，CPU 毫秒级；不需要 GPU，不需要新数据。
- **资源**：1 人周工程 + 1 GPU 日离线回放；服务端 CPU 侧新增 <5ms（目标 p99 仍 <40ms）。
- **落地步骤**：①离线回放 harness（原动作 vs 优化动作，记录 jerk/路径效率/里程碑时间）；②相位检测阈值标定（3 个代表任务：FruitCollection 多物体、PlugCharger 接触、ConveyorSorting 时间受限）；③TOPP + 接缝 QP 实现；④截止期调度器；⑤2³ 析因（phase-aware × seam × deadline）；⑥L2 单任务通道 3 任务 × 2 次。

```python
def estimate_delta(pain, logs):
    sig = pain.signature(logs)                  # per-run observable
    d_succ_obs = regress(logs.success, sig)     # observational prior
    d_succ_cf  = counterfactual_replay(pain, logs)  # offline fix (trajectory pains)
    d_step_cf  = counterfactual_step(pain, logs)
    return Delta(d_succ_obs, d_succ_cf, d_step_cf, evidence="cf")

def leverage(p):
    return (p.d_succ / p.cost, p.d_step / p.cost, p.d_cred / p.cost)

def rank(ledger):
    return sorted(ledger, key=leverage, reverse=True)
```

```python
def detect_phase(obs, prev, cmd, target_kp, hyst=0.1):
    v = np.linalg.norm(obs.ee_pose - prev.ee_pose) / DT
    near = keypoint_distance(obs, target_kp) < EPS_NEAR
    closing = cmd.gripper < prev.gripper - 1e-3
    if closing and near:            return "contact", 0.9
    if closing:                     return "pre_contact", 0.7
```

### 5.3 TOPP：路径-速度分解（I11）

```python
def topp(path, vmax_fn, amax, jmax, bc):
    # path: p(s), s in [0,1]; sample M points
    # variables: sdot_i >= 0
    # minimize sum ds_i / sdot_i  (time)
    # constraints:
    #   |p'(s_i)| * sdot_i <= vmax_fn(s_i)
    #   |p''(s_i)| * sdot_i**2 + |p'(s_i)| * sddot_i <= amax
    #   jerk via finite difference on sddot
    # boundary: sdot_0 from bc.vel
    sdot = solve_convex_qp(path, vmax_fn, amax, jmax, bc)
    return sdot
```

```python
def seam_qp(prev_q, prev_qd, chunk, dt, w_smooth=1.0):
    # variables q_0..q_{T-1}; hard boundary at the seam
    # min sum ||q_i - chunk_i||^2 + w_smooth * sum ||q_{i+1}-2q_i+q_{i-1}||^2
    # s.t. q_0 = prev_q
    #      (q_1 - prev_q) / dt = prev_qd
    #      |q_{i+1} - q_i| <= vmax * dt
    return solve_small_qp(prev_q, prev_qd, chunk, dt, w_smooth)
```

### 5.5 截止期里程碑调度（I11）

```python
def deadline_schedule(milestones, D, now):
    # milestones: (id, w, d_hat, precedence)
    # maximize E[sum w_k * 1[T_k <= D]]
    order = sorted(milestones, key=lambda m: m.w / max(m.d_hat, 1e-6),
                   reverse=True)              # Smith's rule init
    order = list_schedule_with_precedence(order)  # greedy + local swap
    scale = min(1.0, (D - now) / sum(m.d_hat for m in order))
    # scale < 1: speed up free segments; contact segments keep vmax(contact)
    return order, scale
```

## 6. 实验设计（轨迹层 v1）

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0 | P9/P10/P12 反事实回放；phase-aware vs uniform；seam on/off；deadline scaling on/off；\(T_a\) ∈ {4,8,16} | 离线，CPU | 接缝 jerk ↓≥30%；路径时间 ↓≥10% 且路点误差不显著上升；标称场景成功率代理不降 |
| L1 | 2³ 析因（phase-aware × seam × deadline）+ \(T_a\) 三档 | 离线 + 少量真机 | 主效应显著的 ≤3 个组合进 L2 |
| L2 | 3 任务：FruitCollection（多物体）、PlugCharger（接触）、ConveyorSorting（时间受限）；每任务 2 次 | 单任务测试通道（不计分） | 标称 Δsuccess ≥0；多物体 Δstep >0；p99 <40ms；无动作离群告警 |
| 门禁 | PR4：run_client 全流程 + 动作健康度（界内/平滑/离群） | 本地 stub | 0 拒绝动作、p99 <40ms、jerk 不升 |

**任务选择理由**：FruitCollection 覆盖多物体里程碑吞吐；PlugCharger 覆盖接触精度与相位降速；ConveyorSorting 覆盖移动目标与时间压力。三者分别代表 P10/P4/P5 三类痛点，能以最小真机预算验证轨迹层的三种收益。

**关键消融问题**：
1. 相位感知是否真的「free 加速、contact 降速」都有效？还是只有 contact 降速有效？（若 free 加速不增分，砍掉，降低风险。）
2. 接缝 QP 的增益是否独立于相位速度？（若接缝是主因，优先保留最低风险子模块。）
3. 截止期调度在 180s 内是否真的改变完成里程碑数？（用日志回放估计，再用 L2 确认。）

**最值得押注（一句话）**：押 I11「相位感知轨迹优化 + 接缝 C1 + 截止期里程碑调度」作为先手免费分，再用 I10 痛点账本把 I1/I2/I5 的数据引擎预算排到正确位置——在官方单卡即可微调、推理必须确定且动作规律性会被记录的成本结构下，先把执行层的 Pareto 改进拿走，是当前 ROI 最高的一步。
