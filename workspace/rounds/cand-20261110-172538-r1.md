# 第 47 轮（承接第 46 轮 v23；本轮灵感：比赛策略 × 失败恢复） · Compete-Recover：竞赛风险预算驱动的策略证书与有界恢复证书（五层架构 v11）

> 承接第 46 轮 v23 Memory-Safety-Voice。v23 解决了“单次指令-姿态-能量-记忆”的联合决策，但隐含假设 H5：系统运行在一个“无限时间、无对手、失败可无限重来”的准静态环境里。真实 UniBot 比赛恰恰相反：有计分规则与名次压力、有限回合/尝试次数、不可逆失败（摔倒/出界/丢定位）、对手扰动与裁判判罚。两个灵感词精确命中 H5：**比赛策略**迫使把“是否冒险、何时保分、如何分配尝试次数”提升为元决策层；**失败恢复**迫使把“失败后如何在有界时间内重建姿态证书与能量租约”形式化为恢复证书。二者耦合出新问题：**风险预算、策略证书、恢复证书三者如何联合优化，若恢复证书在摔倒/绑架后错误收敛，系统会带着虚假证书继续冒险并把可恢复失败变成不可逆失败**。

## 0. 直觉与动机

**灵感 1（比赛策略 → 风险预算与策略证书）**
直觉：比赛不是“每次都做对”，而是“在名次压力下做期望分最高的选择”。领先时应保分（bank），落后时应提高风险偏好（exploit）；剩余尝试次数越少，越应押注高方差高收益动作。把比赛建模为带时间预算 T_max、尝试次数 N_try、当前得分 S_t 与对手得分分布 σ_opp 的约束马尔可夫决策过程。定义风险预算 ρ_t=(T_rem,N_rem,S_gap,E_t,p_max)，策略证书保证在置信 1-α_s 下最终得分 ≥ S_lb，且不进入不可恢复失败集 F_unrec。

**灵感 2（失败恢复 → 有界恢复证书）**
直觉：失败不可怕，怕的是“失败后以为自己恢复了”。摔倒、丢定位、能量租约过期、SAB 绑定失效都是可检测失败事件 f∈F。恢复不是“再试一次”，而是一个有截止时间 τ_rec(f) 的证书重建过程：必须在截止时间内重新签发姿态证书 P_t^rec、能量租约 ℓ_e^rec、安全绑定 B^rec，否则进入保分/停机。恢复证书 R_t=(P_t^rec,ℓ_e^rec,B^rec,τ_rec,α_rec) 与姿态证书同级，未恢复即 fail-closed。

**灵感 3（策略-恢复耦合 → 三态自动机）**
直觉：比赛策略与失败恢复共享同一个“风险预算”。每次冒险都在消耗恢复余量；每次失败都在消耗尝试次数与时间。于是把系统抽象为 EXPLOIT / RECOVER / BANK 三态自动机：EXPLOIT 追求分数，RECOVER 重建证书，BANK 锁定已认证分数。状态转移由“分数差距 × 剩余预算 × 恢复可行性”共同决定。记忆库（IP-66）中的历史 outcome 必须携带恢复代价 c_rec，否则会检索到“高分但摔过”的危险策略。

**耦合升级（五层 v11）**：在 v10 四层上新增 L0 竞赛元层与 L0.5 恢复层——CML（Competition Meta Layer）做风险预算与三态决策；RCL（Recovery Certificate Layer）做失败分类、恢复算子与有界再认证；SBL（Score Banking Ledger）做认证检查点、回滚与保分账本。原 L1–L4 全部接收 ρ_t 与 R_t：ECPS 用 ρ_t 约束模态冒险，CAR 守卫加入“恢复可行性”，CCA 增加失败注入红队，DCL 采集失败-恢复轨迹。

## 1. 形式化定义（增量：定义 59–63）

**定义 59（竞赛约束 MDP 与得分过程）**
竞赛为 CMDP 𝒞=(S,A,P,R,T,N,F)，其中 T_max 为总时间预算，N_try 为尝试次数，R(s,a) 为即时得分，F 为失败事件集。策略 π_meta:(s,S_t,ρ_t)→a∈{EXPLOIT(a'),RECOVER(f),BANK}。得分过程
S_{t+1}=S_t+R(s_t,a_t)-c_fail·1[f_t∈F]。
对手得分建模为分布 D_opp，名次压力 gap_t=S_target-S_t。

**定义 60（风险预算与策略证书）**
风险预算 ρ_t=(T_rem,N_rem,gap_t,E_t,p_max)，p_max 为允许的不可恢复失败概率上限。风险偏好
λ_t=clip(a·gap_t/(σ_opp+ε) - b·N_rem/N_0 + c·(1-E_t/E_0), λ_min, λ_max)。
**策略证书** C_strat=(π_meta,S_lb,α_s)：
P(S_final≥S_lb ∧ 全程 f∉F_unrec | π_meta,ρ_t)≥1-α_s。

**定义 61（失败分类与可恢复性）**
失败事件 f∈F={PoseLoss,EnergyExpiry,BindFail,Fall,OutOfBounds,SensorDrop}。可恢复谓词 Rec(f,s)∈{0,1}，恢复算子 R_f 把失败后状态映射到恢复态 s_rec。若不存在满足 τ_rec(f) 与 α_rec(f) 的恢复算子，则 f 为不可恢复，记 f∈F_unrec。

**定义 62（有界恢复证书）**
恢复证书 R_t=(P_t^rec,ℓ_e^rec,B^rec,τ_rec,α_rec)，其 soundness：
P(X_t∈P_t^rec ∧ E(t)≥E_min ∧ B(v_t,P_t^rec)≥θ_safe | 恢复在 τ_rec 内完成)≥1-α_rec，
且恢复耗时 Δ_rec≤τ_rec(f)。**恢复失败判据**：Δ_rec>τ_rec(f) 或任一子证书不成立 ⇒ 级联失效，进入 BANK 或停机。

**定义 63（策略-恢复联合目标）**
元策略在恢复选项下的值：
V(s)=max{ max_{a∈A_exploit} [R(s,a)-λ_t·C_unrec(s,a)+γV(s')],
           max_{f∈F_rec} [-c_rec(f)+V(s_rec(f))],
           S_bank }，
约束 P(f∈F_unrec)≤p_max 且 Δ_rec≤τ_rec。**保分判据**：当 S_bank≥S_target 或 ρ_t 耗尽时强制 BANK。

## 2. 新增产出与既有 IP 升级

**IP-69 CML（Competition Meta Layer）**
- 得分模型与对手分布估计：历史成绩/裁判规则→R、D_opp
- 风险偏好控制器：gap×剩余尝试×能量→λ_t
- 三态自动机：EXPLOIT/RECOVER/BANK，带滞回与超时
- 策略证书签发：蒙特卡洛+共形校准给出 S_lb、α_s

**IP-70 RCL（Recovery Certificate Layer）**
- 失败检测器：姿态证书失效/能量租约过期/绑定低/摔倒/出界/传感器掉线
- 恢复算子库：重定位、站稳、重新绑定、模态切换、回滚
- 有界再认证：在 τ_rec 内重建 P_t^rec、ℓ_e^rec、B^rec
- 恢复红队：绑架机器人、镜面重定位、电量骤降注入

**IP-71 SBL（Score Banking Ledger）**
- 认证检查点：仅在联合证书有效时落检查点
- 回滚与保分：回滚到最近认证配置，锁定 S_bank
- 恢复代价账本：记录每次失败的 c_rec 与时间，回灌 MVR

**既有 IP 升级**
IP-63 ECPS：风险预算 ρ_t 进入模态效用，p_max 约束深度冒险
IP-66 MVR：记忆元组加入 c_rec 与 recovery_outcome，屏蔽“高分高恢复代价”记忆
IP-67 VAD：语音指令在 RECOVER 态只允许安全/停止类槽位
IP-68 SAB：绑定失败触发 RECOVER 而非仅入队
IP-51 CAR：守卫加入“恢复可行性 Rec(f,s)”与 τ_rec 截止
IP-62 CCA：新增失败注入、恢复证书覆盖率、虚假恢复检测
IP-45 总线：新增 competition-state / risk-budget / recovery-state / score-bank 话题

## 3. 算法骨架

每控制周期：
1. 读 S_t,ρ_t,s_t，检测失败 f
2. 若 f 非空：进入 RECOVER，调用 R_f 并在 τ_rec 内再认证；超时→BANK/fail-closed
3. 否则算 λ_t，CML 枚举候选计划，按 V(s) 选 EXPLOIT/BANK
4. EXPLOIT 前落认证检查点 cp；执行中若失败→rollback(cp)+RECOVER
5. 若 S_bank≥S_target 或 ρ_t 耗尽→BANK
6. 全过程 RCL 与 CAR 共享证书，任一失效即降级

## 4. 本轮最大风险

**一句话**：恢复证书的最大风险是把“重定位收敛到一个自信但错误的位姿”误判为已恢复——摔倒/绑架后环境外观可能相似，再认证会在错误基座上签发看似 sound 的 P_t^rec，元策略据此继续冒险，把本可恢复的失败变成不可逆失败；因此恢复再认证必须与深度-惯性-已知地标的多模态一致性互检、设置独立于重定位器的恢复审计集，并在任何一致性冲突时默认进入 BANK/fail-closed。

## 2. 关键算法 伪代码

### IP-69 CML
```
def risk_appetite(S_t, S_target, N_rem, N_0, E_t, E_0, sigma_opp):
    gap = S_target - S_t
    lam = a * gap / (sigma_opp + eps) \
        - b * (N_rem / max(N_0, 1)) \
        + c * (1.0 - E_t / max(E_0, 1e-6))
    return clip(lam, LAM_MIN, LAM_MAX)

def plan_value(plan, lam, p_max, T_rem):
    if plan.t_exec > T_rem or plan.p_unrec > p_max:
        return -inf
    return plan.E_score - lam * plan.p_unrec * C_UNREC - plan.time_cost

def cml_decide(state, S_t, rho, lam, cp):
    if S_t >= rho.S_target or rho.T_rem <= T_MIN or rho.N_rem <= 0:
        return BANK, None
    best = max(candidate_plans(state),
               key=lambda p: plan_value(p, lam, rho.p_max, rho.T_rem))
    if best is None or best.E_score < S_bank(cp) + DELTA_BANK:
        return BANK, None
    return EXPLOIT, best
```

### IP-70 RCL
```
FAILURES = [PoseLoss, EnergyExpiry, BindFail, Fall, OutOfBounds, SensorDrop]

def detect_failure(sig):
    for f in FAILURES:
        if f.trigger(sig):
            return f
    return None

def recover(f, state, tau_rec, alpha_rec):
    t0 = now()
    for step in recovery_plan(f):
        if now() - t0 > tau_rec:
            return None
        execute(step)
        if step.restores_cert():
            P_rec = re_certify_pose(state, multimodal=True)
            e_rec = re_certify_energy(state)
            B_rec = safety_bind(state.v_t, P_rec, state.omega_t)
            if P_rec and e_rec and B_rec >= THETA_SAFE:
                if audit_consistency(P_rec, state) >= RHO_CONSIST:
                    return RecoveryCert(P_rec, e_rec, B_rec,
                                        now() - t0, alpha_rec)
    return None

def recovery_plan(f):
    return {
        Fall:         [stand_up, relocalize, re_certify],
        PoseLoss:     [switch_modality(Depth), relocalize, re_certify],
        EnergyExpiry: [shed_load, switch_modality(RGB), re_certify],
        BindFail:     [reask_voice, re_anchor, re_certify],
        OutOfBounds:  [return_safe_zone, relocalize, re_certify],
        SensorDrop:   [switch_modality(backup), re_certify],
    }[f]
```

### IP-71 SBL
```
def make_checkpoint(state):
    if joint_cert_valid(state):
        return Checkpoint(P_t=state.P_t, l_e=state.l_e,
                          config=state.config, S=state.S_t, t=now())
    return None

def bank(cp):
    if cp is None or not cp.verified:
        return None
    return max(S_BANK, cp.S)

def rollback(cp):
    restore_config(cp.config)
    return re_certify(cp.P_t, cp.l_e)
```

### 全局决策 Π_v24
```
def compete_recover_step(state, S_t, rho, cp):
    f = detect_failure(state.signals)
    if f is not None:
        rc = recover(f, state, TAU_REC[f], ALPHA_REC[f])
        if rc is None:
            return BANK, fail_closed(f)
        return RECOVERED, rc
    lam = risk_appetite(S_t, rho.S_target, rho.N_rem, rho.N_0,
                        state.E_t, rho.E_0, rho.sigma_opp)
    action, plan = cml_decide(state, S_t, rho, lam, cp)
    if action == BANK:
        return BANK, bank(cp)
    cp = make_checkpoint(state)
    ok = execute_plan(plan)
    if not ok:
        return RECOVER, rollback(cp)
    return EXPLOIT, ok
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| CML 元决策 | O(|Π_plan|) | O(|Π_plan|) | 风险预算约束下策略证书 S_lb |
| RCL 失败恢复 | O(|F| + |steps|·d) | O(|F|) | τ_rec 内再认证成功 ⇒ R_t sound |
| SBL 检查点/回滚 | O(1) | O(|CP|) | 仅联合证书有效时落点 ⇒ 回滚态可认证 |
| 全局决策 Π_v24 | O(|F| + |Π_plan|) | O(|CP|) | 三态 fail-closed ⇒ 不带着假证书冒险 |

正确性定理（非正式）：若 (i) 每个可恢复失败 f 的恢复算子能在 τ_rec(f) 内以 ≥1-α_rec 重建联合证书，(ii) CML 的候选计划满足 p_unrec≤p_max，(iii) 检查点只在联合证书有效时生成，则闭环系统要么维持 S_t≥S_bank，要么进入显式 fail-closed；不存在“证书已失效但策略层仍 EXPLOIT”的路径。

证明思路：由 (iii) 检查点有效，(ii) 每个 EXPLOIT 计划的不可恢复失败概率受限；失败被 detect_failure 捕获后要么由 (i) 恢复并返回有效 R_t，要么超时进入 BANK。因此 EXPLOIT 态的前置条件恒为有效联合证书。恢复证书本身的 soundness 还需额外的多模态一致性审计（见第 6 节）。

## 4. 实验设计 E115–E120

| 实验 | 指标 | 门槛 |
|---|---|---|
| E115 风险偏好校准 | 不同 gap/N_rem 下的 λ_t 与动作选择 | 落后时冒险率↑、领先时保分率↑；AUC ≥ 0.8 |
| E116 失败恢复成功率 | 各 f 的恢复成功率、Δ_rec | 可恢复类 ≥ 95%；Δ_rec ≤ τ_rec（P95） |
| E117 恢复证书 soundness | 虚假恢复率、覆盖率 | 虚假恢复 ≤ 1%；覆盖率 ≥ 95% |
| E118 保分策略收益 | 与“永远冒险/永远保守”对比得分 | 平均分 ≥ max(baseline)+5% |
| E119 失败注入红队 | 摔倒/绑架/骤降/掉线组合 | 不可恢复失败 ≤ p_max；0 次带假证书 EXPLOIT |
| E120 全流程竞赛演练 | 100 次 dry run 名次分布 | 进入前 20% ≥ 70 次；停机 ≤ 2 次 |

回退策略：E117 虚假恢复 > 2% → 提高一致性阈值 ρ_consist 或禁用记忆恢复、强制人工/裁判复位；E118 保分过度保守 → 提高 λ_min 下限并缩短 BANK 滞回；E119 注入失败超限 → 关闭高风险计划，强制 Depth+IMU 融合再认证。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 重定位自信错误→虚假恢复 | 高 | 多模态一致性审计（深度+IMU+已知地标）；独立审计集；冲突即 BANK |
| 风险偏好过激→不可逆失败 | 高 | p_max 硬约束；尝试次数下限；落后时也保留 BANK 选项 |
| 保分过度→丢分 | 中 | λ_min 下限；BANK 滞回；仅在 S_bank≥S_target 或预算耗尽时锁死 |
| 失败分类漏掉新失败模式 | 中 | 未分类信号默认最保守恢复（停机）；持续回灌 DCL |
| 回滚物理不可行（摔倒无法撤销） | 高 | 区分“状态回滚”与“物理复位”；物理不可逆失败直接进 BANK/裁判复位 |
| 恢复耗时挤占比赛时间 | 中 | τ_rec 计入风险预算；超时立即 BANK |

## 6. 本轮最大风险

**一句话**：恢复证书最危险的失效是“在错误基座上自信地签发 sound 证书”——摔倒/绑架后重定位可能收敛到外观相似的错误位姿，RCL 若只信任单一重定位器就会把虚假恢复当成真恢复，CML 随即继续冒险，把可恢复失败放大为不可逆失败；因此必须以深度-惯性-已知地标的多模态一致性作为恢复证书的独立否决项，并让任何一致性冲突默认落入 BANK/fail-closed。
