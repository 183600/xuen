# 第 47 轮（承接第 46 轮 v23；本轮灵感：多轮对话 × 分层规划） · Dialogue-Hierarchy-Cert：多轮对话驱动的分层任务规划与姿态/能量证书协同（五层架构 v11）

> 承接 v23（MVR × VAD × SAB）与 v10（Energy-Context-Depth）。v23 把语音、记忆与安全绑定串成闭环，但隐含假设 H5：**指令是单轮、独立、原子的，任务结构是扁平的**。真实 UniBot 交互是连续多轮的：用户会说“把左边那个杯子递给我”→“不对，是右边那个”→“算了，先放下”；任务也天然分层（“收拾桌面”→“清理餐具”→“抓取杯子”→“移动末端”）。两个灵感词精确命中 H5：**多轮对话**引入对话状态、指代、澄清、修正与撤销，使指令不再是独立事件；**分层规划**引入目标树与子目标分解，使每个原语动作的观测需求、姿态精度与能量预算各不相同。二者耦合出新的核心问题：**当对话在高层修改/撤销计划时，分层规划必须把变更传播到所有叶子原语，而每层绑定的姿态证书、能量租约、模态决策必须随计划版本一致地级联失效与重签；否则系统会用“仍然 sound 但语义已过期”的证书执行已被取消的子目标（幽灵执行）**。

## 0. 直觉与动机

**灵感 1（多轮对话 → 对话状态与承诺集）**
直觉：一句话的意思取决于它前面说过什么。“右边那个”在没有上一轮时无法 grounding；“算了”撤销的是上一轮承诺而非当前帧。把对话建模为状态 D_t=(U_t,G_t,Γ_t,κ_t)：U_t 意图分布、G_t 指代绑定、Γ_t 活跃承诺集、κ_t 对话版本。VAD 从“解析单句”升级为“更新状态并产出话语行为”（请求/澄清/确认/修正/撤销/告知）。安全上最关键的是 **Γ_t**：只有仍活跃的承诺才允许执行。

**灵感 2（分层规划 → 每层证书与能量预算）**
直觉：抓杯子与收拾桌面需要的观测精度和电量完全不同。用 HTN 任务树 T：根目标分解为子目标，叶子是原语。每个节点 n 标注观测需求 ω_n、证书半径需求 rad_n^req、能量预算 e_n。能量在树上递归分配，证书在叶子上签发、向父节点汇聚成“子目标完成证书”。高层修改只应重规划受影响子树，而非全树。

**灵感 3（耦合 → 版本向量与子树失效传播）**
直觉：多轮对话修改高层计划，若低层仍在执行旧原语，就会出现“计划已换、证书未换”。解决不是加一个检查，而是引入**版本向量 v=(κ_dialogue, v_plan, v_cert)**：任何撤销/修正话语使受影响子树的所有证书版本失效；CAR 守卫要求三者相等才放行；不相等则 fail-closed 或要求澄清。指代跨轮复用时，姿态证书还需满足 τ_ground 与漂移阈值，否则必须重观测。

**耦合升级**：在 v10 四层（根信任 / L1 几何 / L2 上下文 / L3 CAR / L4 DCL）上新增 **对话-计划协同层**，构成五层 v11。DST 产出 D_t 与 Γ_t；HTP 产出带标注的任务树与计划版本；PCB 把计划节点与证书绑定并做版本校验与子树失效；ECPS 从任务树读取分层能量预算；SAB 只对活跃承诺做指令-姿态绑定。既有 IP 全部升级而非推倒。

## 1. 形式化定义（增量：定义 59–64）

**定义 59（对话状态与话语行为）**
对话状态 D_t=(U_t,G_t,Γ_t,κ_t)：U_t∈Δ(Intent) 为用户意图分布，G_t:Ref→2^W 为指代到世界实体/区域的 grounding 映射，Γ_t 为活跃承诺集，κ_t 为对话版本号。话语行为 a_t∈A={request,clarify,confirm,revise,cancel,inform}。状态转移 D_{t+1}=δ(D_t,u_t,a_t)，且当 a_t∈{revise,cancel} 时 κ_{t+1}=κ_t+1。

**定义 60（分层任务树与计划版本）**
任务树 T=(V,E,root)，节点 n 带 (g_n, pre_n, post_n, decomp_n, ω_n, rad_n^req, e_n)。叶子为原语 a。计划 π 是合法分解与原语序列，计划版本 v_plan 在每次重规划时递增。**子树** sub(n) 为 n 及其全部后代。

**定义 61（计划-证书绑定与版本一致性）**
每个活跃原语 a 绑定证书束 C(a)={P_t, ℓ_p, ℓ_e, m_t, (κ, v_plan, v_cert)}。**绑定有效** iff
v_cert(a)=v_plan(π) 且 π 的根对话版本 κ 与当前 D_t 的 κ 一致，且 P_t 未过期、ℓ_e 可行。
**版本失同步**（desync）指存在活跃 a 使上式不成立。

**定义 62（承诺语义与撤销传播）**
承诺 γ=(scope n_γ, content, τ_γ)∈Γ_t。撤销/修正话语命中 scope n 时执行子树失效：
INVALIDATE(sub(n))：∀a∈leaves(sub(n)), v_cert(a)←⊥；并从 Γ_t 移除被撤销承诺。仅当 v_cert(a)≠⊥ 且对应承诺活跃时，原语才可执行。

**定义 63（分层能量预算）**
对节点 n：e_n = Σ_{c∈children(n)} e_c + e_overhead(n)，且须满足 e_n ≤ E_avail(ℓ_e, horizon(n))。对话新增子目标时触发重分配；若不可行，HTP 返回 infeasible 并交由澄清策略处理，而非静默降低证书精度。

**定义 64（跨轮指代证书延续）**
指代 ρ 的 grounding 绑定世界区域 R_ρ，其证书有效期 τ_ground(ρ)。若跨轮姿态漂移 ‖x̂_t−x̂_{t'}‖ > δ_drift 或 t−t' > τ_ground，则复用失效，必须重新观测后再执行，禁止用旧证书解释“右边那个”。

## 2. 新增产出与既有 IP 升级

**IP-69 DST（Dialogue State Tracker）**
- 话语行为分类 + 意图分布更新
- 指代 grounding（对话历史 × 当前感知 × 姿态证书）
- 承诺集 Γ_t 维护与撤销语义
- 对话版本 κ 递增与广播

**IP-70 HTP（Hierarchical Task Planner）**
- HTN 分解 + 每节点观测/证书半径/能量预算标注
- 局部重规划（只重规划受影响子树）与计划版本递增
- 可行性检查：能量或证书需求不可满足时返回 infeasible 而非降精度
- 子目标完成证书向父节点汇聚

**IP-71 PCB（Plan-Certificate Binder）**
- 版本向量 (κ, v_plan, v_cert) 绑定与守卫
- 子树失效传播 INVALIDATE(sub(n))
- 跨轮指代证书延续与漂移检测
- 幽灵执行检测（活跃原语无活跃承诺）

**既有 IP 升级**
IP-66 MVR：记忆键从单指令升级为 (对话摘要, 计划节点, B)，屏蔽已撤销/失败承诺的记忆
IP-67 VAD：多轮输入，输出话语行为与澄清请求，而非直接模态决策
IP-68 SAB：绑定对象改为活跃承诺 γ 而非孤立 v_t；撤销即解绑
IP-63 ECPS：从任务树读取分层能量预算 e_n，按子树分配
IP-61 DCL：澄清失败样本与 desync 样本进入采集任务
IP-62 CCA：新增版本失同步红队、撤销传播测试、指代漂移注入
IP-51 CAR：守卫加入 v_cert=v_plan 且承诺活跃
IP-45 总线：新增 dialogue-state / plan-version / cert-version / commitment 话题

## 3. 算法骨架

每轮对话：
1. ASR/NLU → 话语行为 a_t 与槽位
2. DST 更新 D_t，必要时 κ←κ+1，维护 Γ_t
3. 若 a_t∈{revise,cancel}：PCB 对命中 scope 执行 INVALIDATE(sub(n))
4. HTP 局部重规划受影响子树，v_plan←v_plan+1，重分配 e_n
5. 若 grounding 置信 < τ_g 或能量不可行 → 生成澄清请求（clarify），不执行
6. PCB 为叶子原语重签证书束，检查 v_cert=v_plan=κ 一致
7. SAB 仅对活跃承诺做指令-姿态绑定；CAR 用版本向量守卫
8. 执行；失败或 desync → fail-closed 并回灌 DCL

## 4. 本轮最大风险

**一句话**：多轮对话中的撤销/修正若未在控制周期内传播为计划子树失效，系统会拿版本不匹配但几何上仍然 sound 的证书执行已被取消的子目标（幽灵执行），“安全证书”反而成为错误语义的通行证；因此必须以版本向量强制对话-计划-证书三者同步，任一失配即 fail-closed 并要求澄清。

## 2. 关键算法 伪代码

### IP-69 DST
```
def dst_update(D_prev, u_t, percept, cert):
    a_t = classify_dialogue_act(u_t)           # request/clarify/revise/cancel...
    U_t = bayes_update(D_prev.U, u_t, a_t)
    G_t = ground_references(u_t, D_prev.G, percept, cert)  # 指代->世界区域
    if a_t == 'cancel':
        target = resolve_scope(u_t, D_prev.G)
        Gamma_t = D_prev.Gamma - commitments_at(target)
    elif a_t == 'revise':
        target = resolve_scope(u_t, D_prev.G)
        Gamma_t = (D_prev.Gamma - commitments_at(target)) | {new_commitment(u_t)}
    else:
        Gamma_t = D_prev.Gamma | {make_commitment(u_t)} if a_t == 'request' else D_prev.Gamma
    kappa = D_prev.kappa + (1 if a_t in ('revise', 'cancel') else 0)
    return D_t(U_t, G_t, Gamma_t, kappa), a_t
```

### IP-70 HTP
```
def htp_plan(goal, T_prev, D_t, lease_e, calib):
    n_hit = locate_scope(goal, T_prev)
    if n_hit and not affected_by(D_t, n_hit):
        return T_prev, T_prev.version            # 未受影响，复用旧计划
    subtree = htn_decompose(goal, calib)          # goal -> subtasks -> primitives
    annotate(subtree)                             # 每节点 ω_n, rad_n^req, e_n
    if not budget_feasible(subtree, lease_e):
        return None, 'infeasible'                 # 交由澄清，不降精度
    T_new = graft(T_prev, n_hit, subtree)
    T_new.version = T_prev.version + 1
    return T_new, T_new.version

def budget_feasible(node, lease_e):
    need = sum(e_n for n in leaves(node))
    return need <= E_avail(lease_e, horizon(node))
```

### IP-71 PCB
```
def invalidate_subtree(T, n):
    for a in leaves(sub(n)):
        a.cert.v_cert = None                       # 证书版本置空
    return T

def bind_certificate(a, P_t, lease_e, m_t, kappa, v_plan):
    v_cert = (kappa, v_plan, next_serial())
    a.cert = Cert(P_t, lease_e, m_t, v_cert)
    return a.cert

def version_guard(a, D_t, T):
    if a.cert is None or a.cert.v_cert is None:
        return False
    k, vp, vc = a.cert.v_cert
    return (k == D_t.kappa) and (vp == T.version) and (vc is not None) \
           and lease_valid(a.cert.lease_e, t+Delta, E_min) \
           and commitment_active(a, D_t.Gamma)

def ghost_execution_check(T, Gamma):
    return [a for a in active_primitives(T) if not commitment_active(a, Gamma)]
```

### 对话-计划-证书主循环
```
def dialogue_plan_loop(u_t, D_prev, T_prev, lease_e, calib, S_phi):
    D_t, a_t = dst_update(D_prev, u_t, percept(), cert())
    if a_t in ('revise', 'cancel'):
        n = resolve_scope(u_t, D_t.G)
        T = invalidate_subtree(T_prev, n)
    else:
        T = T_prev
    T, status = htp_plan(D_t.U.argmax(), T, D_t, lease_e, calib)
    if T is None:                                  # 能量/证书需求不可行
        return clarify(D_t, reason='infeasible')
    if grounding_conf(D_t) < tau_g:                # 指代不明确
        return clarify(D_t, reason='ambiguous')
    for a in leaves(T):
        m_t = ecps_schedule(a.omega, D_t, lease_e)  # 分层预算约束
        bind_certificate(a, pose_certify(m_t), lease_e, m_t, D_t.kappa, T.version)
    if ghost_execution_check(T, D_t.Gamma):
        return 'fail-closed', 'ghost'
    for a in execution_order(T):
        if not version_guard(a, D_t, T):
            return 'fail-closed', 'desync'
        if not sab_bind(a, D_t.Gamma):
            return 'queue', a
        execute(a)
    return 'success', T.version
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| DST 更新 | O(|Ref|·|W|) | O(|Γ|+|G|) | κ 单调递增，撤销后旧承诺不可执行 |
| HTP 局部重规划 | O(|sub(n)|·b) | O(|T|) | 只重规划受影响子树，其余计划版本不变 |
| PCB 失效传播 | O(|leaves(sub(n))|) | O(|T|) | 撤销后子树证书 v_cert=⊥，无法通过守卫 |
| 版本守卫 | O(1) 每原语 | O(1) | v_cert=v_plan=κ 且承诺活跃才放行 |
| 全局循环 | O(|T|) | O(|T|+|Γ|) | 版本一致 + 承诺活跃 + 能量可行三重 fail-closed |

正确性定理：设对话版本 κ、计划版本 v_plan、证书版本 v_cert。若某原语 a 被执行，则执行前 version_guard(a)=True，即 v_cert(a)=v_plan(T)=κ(D_t) 且 a 对应承诺 γ∈Γ_t 活跃且 ℓ_e 可行。若发生 revise/cancel，INVALIDATE(sub(n)) 使受影响叶子 v_cert=⊥，任何旧证书都无法通过守卫；HTP 仅在能量与证书需求均可行时签发新计划，否则返回澄清。因此不存在“活跃原语使用已撤销承诺的证书”的幽灵执行，除非版本向量被绕过。

## 4. 实验设计 E115–E120

| 实验 | 指标 | 门槛 |
|---|---|---|
| E115 对话状态跟踪 | DST joint goal accuracy；指代 grounding 准确率 | 联合目标准确率 ≥ 80%；grounding ≥ 85% |
| E116 分层规划 | 子目标完成率；局部重规划比例 | 子目标完成率 ≥ 90%；局部重规划 ≥ 70% |
| E117 计划-证书版本一致性 | desync 检出率；幽灵执行次数 | 检出率 100%；幽灵执行 0 次 |
| E118 撤销传播延迟 | INVALIDATE 到守卫生效的周期数 | ≤ 1 个控制周期 |
| E119 分层能量预算 | 预算超支率；澄清触发率 | 超支 0 次；澄清率 ≤ 10% |
| E120 100h 多轮闭环 | 任务成功率；澄清次数；安全违例 | 成功率 ≥ 92%；澄清 ≤ 1 次/任务；违例 0 |

回退策略：E115 grounding < 70% → 关闭跨轮指代复用，强制每轮重观测；E117 出现任一幽灵执行 → 全局切换到“每原语即时校验承诺 + 版本向量”，并停用记忆复用；E119 预算不可行率 > 20% → 提升澄清优先级并降低单任务能量上限；E120 安全违例 > 0 → 强制 fail-closed 模式并回滚到 v23 单轮交互。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 撤销话语 scope 解析错误，失效范围过大或过小 | 高 | scope 置信 < τ_scope 时要求澄清；默认失效范围取保守上界 |
| 跨轮指代 grounding 漂移导致抓错物体 | 高 | τ_ground + δ_drift 双阈值；超限强制重观测并重签证书 |
| 局部重规划破坏父节点后置条件 | 中 | 重规划后校验 pre/post 链；失败则回退全树规划 |
| 分层能量预算在深层子树低估 overhead | 中 | e_overhead 用审计集上界标定；预留 10% 安全余量 |
| 版本向量被异步总线延迟绕过 | 高 | CAR 守卫内同步读取本地版本快照；总线仅作通知，不作权威 |
| 澄清过多导致交互体验下降 | 低 | 澄清策略按信息增益排序，限制每任务澄清预算 |

## 6. 本轮最大风险

**一句话**：多轮对话的撤销/修正若因 scope 解析错误或总线异步延迟而未传播到对应计划子树，系统会用版本不匹配但几何上仍 sound 的证书执行已被取消的子目标（幽灵执行），“安全证书”反而成为错误语义的通行证；因此必须以本地同步版本向量强制对话-计划-证书三者一致，任一失配即 fail-closed 并要求澄清。
