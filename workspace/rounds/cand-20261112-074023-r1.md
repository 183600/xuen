# 第 58 轮（承接第 57 轮「少样本×跨模态×个性化」IP-133~138；灵感循环第 1 轮；本轮灵感：「安全交互」×「角色一致性」）

> 第 57 轮把"证据说可信"做到了极致：少样本可校准、跨模态可对账、个性化有界。但它默认了一个从未被检验的前提——**做判断、给证据、下承诺的"角色"是唯一且恒定的**：机器人始终是"被授权的执行者"，人始终是"审批者"，同一份证据与同意可以在任何阶段复用。真实部署里角色沿三个维度流动：时间（侦查→搬运→救援）、主体（机器人↔人↔多机）、权限（提议/审批/监督）。第 57 轮的个性化只刻画了操作者的**能力**（cal/vig/auth），没有刻画操作者的**权责身份**，更没有刻画系统自身角色的**一致性与可交接性**。于是留下两个新盲点：**(a) 角色洗白**——侦查角色采集的证据被静默挪用到不可逆操作角色上，"旧证据 + 新权限"绕过证据门；**(b) 角色漂移/脑裂**——声明的是顾问，执行的是执行者；交接时旧持有者与新持有者同时自认有权，或旧持有者拿过期授权继续动作。本轮两个灵感合流为一条更完整的交互安全命题：**安全交互 = 物理包络 ∧ 权责对齐 ∧ 角色可读**；**角色一致性 = 证据/同意/权限都绑定到带栅栏的角色租约，且交接是原子事务**。

核心矛盾：
- **H29（角色边界 vs 证据惯性）**：证据一旦取得就想被复用，但证据只在产生它的角色/作用域内有效；重新认证昂贵，于是存在把证据"洗白"到更高权限角色的持续压力——安全门挡得住"证据不足"，挡不住"证据越权"。
- **H30（严格一致 vs 活性）**：角色一致性的本质是互斥（同一角色任一时刻只有一个合法持有者），但互斥与可用性天然冲突：审批者离席、网络分区、多机切换时，严格一致会导向"永远安全停"，系统变得不可用。必须给交接一个有界时间与降级自主模式。
- **H31（一致 vs 正确）**：可以在一个**错误**的角色设计上把一致性做到完美。栅栏、租约、绑定、审计都能通过，而角色格本身把不该给的权限给了错的人——结构性一致会制造"已经安全"的假象。

## 0. 直觉与动机

**灵感 1（安全交互 → 交互安全的三个合取项）**
直觉：物理安全是交互安全的必要条件，不是充分条件。一个"脚下不摔、接触不坏"的机器人，如果做了从未被授予的动作，仍然是**不安全的交互**。把交互安全拆成三个必须同时成立的合取项：**(i) 物理包络**（第 53–57 轮的接触/步态/证据约束）；**(ii) 权责对齐**（此刻发起的动作，其角色、作用域、审批链都与授权一致）；**(iii) 角色可读**（人与机器人对"谁在什么角色、能做什么、授权何时失效"持有同一个可核对模型）。三者缺一，物理上没出事也只是运气。

**灵感 2（角色一致性 → 角色即带栅栏的租约）**
直觉：角色一致性本质是分布式系统问题，而不是提示词问题。角色是一份**租约**：任一时刻至多一个合法持有者；交接时旧持有者的动作必须**变得不可能**，而不只是"被劝阻"。解法是经典而严谨的**单调栅栏令牌（fencing token）**：每次角色转移 epoch 自增并写入栅栏号，任何动作只有携带"当前栅栏号且租约未过期"才被放行；旧持有者的迟到动作一律拒绝。这样"脑裂"与"幽灵审批者"都被结构性地排除，而非依赖对端自觉。

**灵感 3（角色漂移与角色洗白 → 声明与执行的持续对账）**
直觉：危险很少以"我要越权"的形式出现，而是以"顺手"的形式出现——声明的是顾问，做着做着开始执行；侦查证据被直接拿去做不可逆接触。于是需要两类持续监控：**漂移 D_role**（声明能力包络 vs 实际动作包络的风险加权对称差）与**洗白 L_role**（被使用的证据/同意，其角色戳或栅栏号与当前角色不符的证据质量之和）。任一超阈，不辩论、不弹窗，直接把角色降到最受限的 meet，并触发重新认证。

**灵感 4（职责分离与操作者角色新鲜度 → 提议者 ≠ 审批者）**
直觉：第 57 轮用 cal/vig/auth 度量"这个人靠不靠谱"，却没问"这个人此刻是否仍在其有权审批的角色上"。把操作者也角色化：proposer / approver / supervisor / bystander / trainee，并加**新鲜度租约**——审批只在审批者当时确实持有 approver 角色、租约在 τ_fresh 内、且与提议者是不同主体时有效。不可逆动作强制两人规则（separation of duty）：同一个人不能既提议又批准。这样"幽灵审批"（人已离席，系统仍按旧授权放行）与"自批自"都被堵死。

**灵感 5（增量合流 → 角色门、角色证书、角色化解释与交接叙事）**
直觉：第 57 轮证据门的五类证据，全部再叠一层**角色绑定谓词**；新增证书 **J_r**（角色分配、租约/栅栏、交接日志、漂移日志、职责分离日志、证据角色绑定）；PCE++ 在检查点前插入角色检查与带栅栏交接；解释内容增加"当前角色/作用域/有效期/改变角色的条件"，且**说做必须一致**——一旦声明角色与实际角色不符，解释只允许给"安全停/绕行"，不允许给行动建议。角色一致性由此从"权限系统"上升为"可解释的安全交互"。

## 1. 形式化定义（增量：定义 139–144）

**定义 139（角色契约格 RCL）** 角色 ρ=(id, S_ρ, C_ρ, F_ρ, D_ρ, α_ρ)：作用域、许可动作类、禁止动作类、义务、授权级。偏序 ρ₁⊑ρ₂ ⇔ C_{ρ₁}⊆C_{ρ₂} ∧ F_{ρ₁}⊇F_{ρ₂}（ρ₁ 更受限）；meet ∧ 给出"最受限公共角色"，用作降级目标。角色分配 A=(agent,ρ,epoch,fence,[t₀,t₁],cert)。一致性谓词 conf(x,ρ) ⇔ cls(x)∈C_ρ ∧ cls(x)∉F_ρ ∧ scope(x)⊆S_ρ。**角色-证据绑定** bind(e)=(ρ_e,S_e,f_e)；证据可复用当且仅当 S_e⊆S_ρ ∧ ρ_e 与 ρ 相容 ∧ f_e≥fence(ρ)。

**定义 140（角色租约与栅栏 RLF）** 角色权威是租约 L_ρ=(holder,epoch,fence,ttl)。安全不变式：任意实际时间窗内每个角色至多一个有效租约；每次成功获取令 fence 严格自增；动作执行要求 lease.valid(t) ∧ lease.holder=actor ∧ lease.fence=fence(ρ)。**原子交接** handoff(ρ,old→new)：①quiesce 停止新承诺，仅允许安全停；②drain 在飞动作在 T_drain 内完成或取消；③restamp 证据按新角色重认证，失败即丢弃；④refresh 刷新同意域，旧同意不随角色迁移；⑤fence++ 并签发新 epoch 租约；⑥审计后解冻。

**定义 141（角色漂移与洗白监控 RDM）** 声明包络 Ĉ(t)=env(ρ.declared)，执行包络 ĉ(t)=env(action_log[t−W,t])。漂移 D_role=risk-weighted symdiff(Ĉ,ĉ)；洗白 L_role=Σ_{e used} mass(e)·1[ρ_e≠ρ ∨ f_e<fence(ρ)]。规则：L_role>θ_L ⇒ 判洗白、强制 ρ←ρ∧ρ_min、全部相关证据重认证；D_role>θ_drift ⇒ 判漂移、降级并冻结升级通道；二者均记入 J_r。

**定义 142（职责分离交互协议 RIP）** 每个不可逆决策含提议角色 π 与审批角色 α：principal(π)≠principal(α)；α 必须持有**新鲜租约**（age≤τ_fresh）且 conf(x,α)；人侧角色 o_role∈{proposer,approver,supervisor,bystander,trainee}，第 57 轮 auth 仅在 o_role 与其匹配时可用。角色转换需显式确认（ack），未确认期间旧角色不保留任何审批权。

**定义 143（角色感知证据门 RGE 与证书 J_r）** 在 FSE 五类证据之上统一追加：binding_valid(e,ρ,fence) ∧ ¬laundered(e) ∧（不可逆 ⇒ SoD）。新增**EV-role**：独立监控者出具的"动作确在角色内"证明，仅作辅助佐证，永不替代物理证据、永不单独放行不可逆接触。J_r=(role_assignments,leases,fences,handoff_log,drift_log,laundering_log,sod_log,evidence_role_bindings)，继承 J_p 全检。

**定义 144（角色一致解释与交接叙事 RCH）** 解释元组由五元组扩为八元组 Exp=(r,b_r 摘要,违反约束,裕度,建议,当前角色/作用域,有效期/栅栏,改变角色的条件)。渲染前做**说做一致检查** stated_role(Exp)=enacted_role(ρ)；不等则只渲染安全停/绕行。角色交接必须叙事（谁、为何、何时生效、旧授权已失效），并要求人侧在 τ_ack 内确认，否则保持冻结。

## 2. 关键算法伪代码（完整版见产物区）

```python
def execute_under_role(role, holder, action, lease):   # IP-140
    if not lease.valid(now) or lease.holder != holder or lease.fence != role.fence:
        return Reject('stale_or_nonholder')            # 栅栏拒绝：过期角色永不复活
    if not role_conform(role, action):
        return Reject('out_of_role')
    if action.irreversible and not separation_of_duty(role, action):
        return Reject('no_sod')                        # 提议者 ≠ 审批者
    return Execute(action)

def role_drift_monitor(role, declared_env, action_log, evidence_use):  # IP-141
    D = risk_weighted_symdiff(declared_env, envelope(action_log[-W:]))
    L = sum(mass(e) for e in evidence_use
            if e.role_stamp != role.id or e.fence < role.fence)
    if L > theta_L:   return force(role.meet(R_MIN)), 'laundering'
    if D > theta_drift: return force(role.meet(R_MIN)), 'drift'
    return role, 'ok'
```

## 3. 复杂度与正确性（要点）

| 组件 | 时间 | 空间 | 正确性关键 |
|---|---|---|---|
| RCL | O(\|C_ρ\|) 判定/动作 | O(\|ℛ\|·\|C\|) | 角色格单调、meet 存在（A41） |
| RLF | O(1)/动作；交接 O(T_drain) | O(\|ℛ\|) | 单持有者、栅栏单调、过期即拒（A42） |
| RDM | O(W)/检查点 | O(W+\|ℛ\|) | 洗白/漂移可检出、降级单向（A43） |
| RIP | O(1)/决策 | O(\|角色\|) | 提议≠审批、审批租约新鲜（A44） |
| RGE | O(\|σ\|) | O(\|σ\|) | 证据角色绑定完备、EV-role 不越级 |
| RCH | O(1) | O(\|Exp\|) | 说做一致、交接需 ack |

**正确性定理（Role-Consistent Interaction Soundness, RCIS）**：在 A33–A40 之上加 **(A41)** 角色契约诚实（C/F/scope 反映真实权限，无影子能力）；**(A42)** 租约安全（单持有者、栅栏严格单调、过期动作被拒、交接有界）；**(A43)** 绑定完备（无证据/同意可跨角色迁移而不重认证，洗白可检出）；**(A44)** 职责分离与新鲜度（不可逆须提议≠审批，审批租约 age≤τ_fresh，操作者角色新鲜）。则：(i) **无幽灵/脑裂承诺**：在 A42 下，过期或非持有者的不可逆提交概率 ≤δ_stale+δ_clock；(ii) **无角色洗白**：跨角色证据复用被拒概率 ≥1−δ_bind；(iii) **交互健全性**：P(unsafe interaction) ≤ Σ_cp[物理项] + δ_role + P(角色格误设)；其中最后一项是**结构性不变量无法内部证明**的诚实缺口；(iv) **活性**：交接在 T_drain+τ_ack 内完成，否则落入安全停，不存在无限冻结。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 角色格误设（一致但错误） | 高 | 最小权限默认 + 角色即代码评审 + 外部红队审计 + 把"角色设计"单列为安全案例 |
| 严格互斥拖垮可用性 | 中高 | 有界交接 + 预授权 standby + 降级自主（仅更小作用域） |
| 操作者角色混淆/疲劳 | 中 | 角色新鲜租约 + 显式 ack + 界面对齐 |
| 栅栏依赖墙钟 | 中低 | 用逻辑 epoch/单调计数器，不依赖墙钟；偏移仅影响 ttl |
| 解释与角色不一致 | 低 | 渲染前 stated=enacted 运行时校验，失败即安全停 |

## 6. 本轮最大风险

**一句话**：角色一致性只能保证"角色簿记自洽"，不能保证"角色设计正确"——一个栅栏、绑定、审计全部通过却把错误能力授予错误主体的角色格，会让系统获得"已经一致所以安全"的假保证，因此本轮真正的赌注从"证据质量"转移到了"角色规格质量"，必须用最小权限、角色即代码评审与外部红队把这项结构性假设钉死，否则一致性越完美、错误越隐蔽。

## 2. 关键算法伪代码

### IP-139/140 RCL+RLF（角色契约与带栅栏租约）

```python
def role_conform(role, x):
    return cls(x) in role.C and cls(x) not in role.F and scope(x) <= role.S

def merge_roles(r1, r2):
    return Role(scope=r1.S & r2.S,
                cap=r1.C & r2.C,           # 许可取交：更保守
                forb=r1.F | r2.F,          # 禁止取并：更保守
                duty=r1.D | r2.D,
                auth=min(r1.alpha, r2.alpha))

def handoff(role, old, new, M, consent):
    freeze(role)                            # ① 停止新承诺，只允许安全停
    drain(role, deadline=T_drain)           # ② 在飞动作完成或取消
    restamp_evidence(M, role, new)          # ③ 证据按新角色重认证，失败即丢弃
    refresh_consent(consent, role, new)     # ④ 旧同意不随角色迁移
    role.fence += 1; role.epoch += 1        # ⑤ 栅栏单调自增，旧持有者立即失效
    lease = issue_lease(holder=new, epoch=role.epoch, fence=role.fence, ttl=T_lease)
    audit.log(('handoff', role.id, old, new, role.fence))
    unfreeze(role)                          # ⑥ 审计后解冻
    return lease

def execute_under_role(role, holder, x, lease):
    if not lease.valid(now) or lease.holder != holder or lease.fence != role.fence:
        return Reject('stale_or_nonholder')  # 栅栏拒绝，过期角色永不复活
    if not role_conform(role, x):
        return Reject('out_of_role')
    if x.irreversible and not separation_of_duty(role, x):
        return Reject('no_sod')
    return Execute(x)
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| RCL | O(\|C_ρ\|)/动作 | O(\|ℛ\|·\|C\|) | 角色格单调、meet 存在（A41） |
| RLF | O(1)/动作；交接 O(T_drain) | O(\|ℛ\|) | 单持有者、栅栏单调、过期即拒（A42） |
| RDM | O(W)/检查点 | O(W+\|ℛ\|) | 洗白/漂移可检出、降级单向（A43） |
| RIP | O(1)/决策 | O(\|角色\|) | 提议≠审批、审批租约新鲜（A44） |
| RGE | O(\|σ\|) | O(\|σ\|) | 绑定完备、EV-role 仅辅助 |
| RCH | O(1) | O(\|Exp\|) | 说做一致、交接需 ack |
| PCE++ | O(\|CP\|·(k_p+k_c)·(C_VOI+d_φ)+\|CP\|·A\*) | O(\|V\|+\|σ\|) | 角色无效即安全停、交接有界 |

**正确性定理（Role-Consistent Interaction Soundness, RCIS）**
假设 A22–A32（第 53–55 轮）、A33–A40（第 56–57 轮）成立；**(A41)** 角色契约诚实：C_ρ/F_ρ/S_ρ 反映真实权限，无影子能力；**(A42)** 租约安全：每角色至多一个有效持有者、栅栏严格单调、过期/非持有者动作被拒、交接在 T_drain+T_ack 内有界；**(A43)** 绑定完备：任何证据/同意跨角色复用必须重新认证，洗白可检出；**(A44)** 职责分离与新鲜度：不可逆动作提议者≠审批者，审批租约 age≤τ_fresh，操作者角色与 auth 匹配。则：

1. **无幽灵/脑裂承诺**：在 A42 下，过期或非持有者对不可逆动作的成功提交概率 ≤ δ_stale + δ_clock；交接期间系统只可能安全停。
2. **无角色洗白**：跨角色复用证据被拒概率 ≥ 1 − δ_bind；EV-role 不能单独放行任何不可逆接触。
3. **交互健全性**：令 unsafe interaction = 物理越界 ∨ 权责越界 ∨ 角色不可读，则

```
P(unsafe) ≤ Σ_cp (δ_f + ε_meta + δ_probe + ε_h + δ_ood·α_conf + δ_xm·1[L1] + δ_role)
            + P(𝓜 陈旧未检出) + P(护盾回退失败) + P(角色格误设)
```

其中 δ_role = δ_stale + δ_clock + δ_bind + δ_drift；**P(角色格误设) 是结构性不变量无法内部证明的诚实缺口**——ACIS 证明的是"只要角色设计正确，交互就安全"，不是"角色设计正确"。
4. **活性**：交接在 T_drain+τ_ack 内完成或进入安全停，不存在无限冻结；角色无效不会导致"卡死但继续动作"。

关键：**角色即租约**（互斥与防僵尸由栅栏结构性保证，不靠对端自觉）；**证据即受角色约束的凭证**（没有跨角色自由迁移的证据）；**人即有权责新鲜度的主体**（能力不等于资格）；**一致性只管簿记自洽，不管角色设计正确**——后者必须留给外部审计。

## 6. 本轮最大风险

**一句话**：角色一致性只能保证"角色簿记自洽"，不能保证"角色设计正确"——一个栅栏、绑定、审计全部通过却把错误能力授予错误主体的角色格，会让系统获得"已经一致所以安全"的假保证，因此本轮真正的赌注从"证据质量"转移到了"角色规格质量"，必须用最小权限、角色即代码评审与外部红队把这项结构性假设钉死，否则一致性越完美、错误越隐蔽。
