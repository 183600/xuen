# 第 2 轮（灵感循环 v2：「云端协同」×「快速原型」）—— 从「单点策略」到「云边协同 + 可快速原型化的策略系统」

> **承接与定位**：第 1 轮的 UIP-01~10 解决的是「在一个远程 API 进程内如何把单模型用得更好」。本轮承认一个更硬的事实：这个 API 本身是**分布式系统**（云端 GPU 服务 ↔ N 台真机），而研究过程本身是**一条迭代流水线**（32 任务 × 5 泛化轴 × 稀缺真机时段）。因此本轮不新增模型结构，而新增两个「基座」：**运行时基座（云边异步协同）** 与 **迭代基座（任务契约编译器 + 多保真原型场）**。UIP-01/07/08 降级为组件，UIP-11~20 为新增点。

## 0. 事实与边界（沿用第 1 轮，不新增未核实事实）

- 评测方式：选手把模型部署为远端 `observation→action` API；评测系统连接 N 台真机，要求连续端口 `8765..8765+N-1`，并记录每步响应延迟及其波动、动作统计规律性，用于结果可信度判定。
- 接口抓手：`metadata{control_space, obs_delta_indices, image_resize, action_chunk_size T_a, token}`、`get_action(obs)`、`reset()`；observation 含 4 路图像、双臂关节/EE 位姿、夹爪、lower_body 与 `observation.language`。
- 计分口径：平均成功率 + 步骤分（step score）；32 项任务、约 32000 episodes / 169 小时公开数据；官方榜单与运行记录仍为 Coming Soon，飞书规则手册正文尚未取得。
- **本轮纪律**：以上事实不变；下文所有「真机」数字均标注为**合成机制检验（synthetic mechanism check）或代理指标**，不冒充赛事结论。新增内容是设计推断，不引入未经核实的新赛事事实。

## 1. 两个灵感词：直觉 → 严谨定义

### 1.1 云端协同

**直觉**：不是「把模型放上云」，而是**让云和边承担不同的时间尺度**。云做慢而重的事（语义规划、子目标核验、世界模型预演、跨任务记忆）；边做快而轻的事（每步动作、反射、安全投影）。协同的关键不是「连得上」，而是**云的建议迟到时不拖累控制回路**。如果把云当成同步 oracle，就会用云的网络抖动去污染每一步的响应延迟——恰好撞上赛事的可信度检查。

**严谨定义（两速率建议系统 / two-rate advisory system）**：
设边缘策略为
\[
\pi_e: \mathcal O\times\mathcal H \to \mathcal A^{T_a},
\]
云端策略为
\[
\pi_c: \mathcal O\times\mathcal H \to \mathcal M,
\]
其中建议消息
\[
m=(g,\tilde a,\tau,c,u,\mathrm{ttl}) \in \mathcal M
\]
包含子目标/技能身份 `g`、可选动作先验 `ã`、云侧时间戳 `τ`、置信度 `c`、不确定度 `u` 与生存期 `ttl`。在边缘时刻 `t`，建议年龄为
\[
\Delta_t=t-\tau.
\]
门控变量
\[
\lambda_t=\mathbf 1[\Delta_t\le \mathrm{ttl}(g)]\cdot
\mathbf 1[c\ge c_{\min}]\cdot
\mathbf 1[d(m,o_t)\le \rho],
\]
其中 `d` 是建议与当前观测的一致性距离（视觉/几何/语言核验），`ρ` 是一致性阈值。边缘动作为
\[
a_t=\Pi_{\mathcal S(o_t)}\!\left((1-\lambda_t)a_t^{e}+\lambda_t a_t^{m}\right),
\]
`Π_S` 是安全投影，`S(o_t)` 是局部安全集（关节/速度/碰撞/夹爪约束）。

**推论 1（非阻塞临界路径）**：若 `a_t` 只依赖本地观测、历史与**已到达**的建议，则每步响应延迟的分布与纯边缘系统相同；云 RTT 只改变 `λ_t`（建议是否可用），不进入 critical path。同步云调用的延迟方差则直接叠加到响应分布上。
**推论 2（TTL 的最优形状）**：若建议的期望收益 `G(Δ)` 随年龄非增、切换风险 `κ` 为常数，则接受集合是前缀区间 `[0,τ*]`，其中 `τ*=max{Δ:G(Δ)>κ}`；这给出了 TTL 的显式定义，而不是拍脑袋的超参。
**推论 3（选择性上云的阈值性）**：若边缘不确定度 `u_t` 越高，云建议的收益 `B(u)` 越大（非减），而等待成本 `c_d` 近似常数，则 `B(u)-c_d` 非减，存在阈值 `u*`：只在 `u_t≥u*` 时同步上云，其余时刻走异步/本地。这样把「云依赖」限制在少数高不确定决策上，避免全局阻塞。

### 1.2 快速原型

**直觉**：不是「训练更快」，而是**把从想法到可信证据的回路缩短**。32 个任务无法靠人手一个个写评测；真机时段不可反复试；所以要把任务规格编译成可执行契约，用多保真评测逐级淘汰，只把少数候选送上真机。快速原型的本质不是「少做事」，而是**把失败尽量提前到便宜、可复现的层级**。

**严谨定义（任务契约 + 保真阶梯）**：
任务 `k` 的契约是一个七元组
\[
\mathcal C_k=(L_k,G_k,\Phi_k,\Psi_k,S_k,\Pi_k),
\]
其中 `L_k` 是语言指令/别名；`G_k` 是有向无环子目标图；`Φ_k` 是每个子目标的**可观测监视器** `φ_v: O×H → {0,1}×[0,1]`（状态 + 置信度）；`Ψ_k` 是计分步权重（`Σψ=100`）；`S_k` 是五类泛化轴上的扰动套件；`Π_k` 是晋级策略。编译器
\[
\mathcal K:(\mathcal D_k,\mathcal C_k)\mapsto(\mathcal M_k,\mathcal P_k,\mathcal J_k)
\]
把数据集卡片与契约编译为**可执行监视器** `M_k`、**扰动配置** `P_k` 与**代理评分器** `J_k`。
保真阶梯 `F0⊂F1⊂F2⊂F3` 分别为：静态帧谓词单测（秒级）、开环回放（分钟级）、闭环回放/学习动力学（小时级）、真机（天/时段级）。晋级策略 `Π_k` 是一个多保真 racing 算法：在低保真层淘汰明显坏的候选，只在存活者上花高保真预算。

**推论 4（「快」必须可度量）**：至少报告四个量——首次可评测时间 TTC、监视器判别力（TPR/TNR/AUROC）、代理与真机的秩相关（Spearman）、晋级精确率（被晋级者中真正优于现任的比例）。没有这四个量，「快速原型」只是主观感觉，无法作为研究贡献。

## 2. 对第 1 轮两个「隐性单点」的诊断

- **UIP-01 的验证器是同步的**：它用 `V(o_t,l,g)` 在 chunk 之间做核验。三重护栏（`k`、`conf_thr`、`max_retry`）控制的是**超时**，不是**延迟方差**；每步延迟的 p99/标准差仍会被 VLM 推理污染，而可信度检查恰恰看这个。→ 需要把验证器移到云侧并异步化（UIP-11），本地只保留轻量 gate。
- **UIP-07 的 RRV 只是回放**：它没有「从任务规格自动生成监视器/扰动/计分」的编译器，也没有多保真晋级的统计纪律。→ 需要把 RRV 升级为 PROTOFORGE（UIP-12），否则 32 个任务的手工 wrapper 会成为真正的瓶颈。
- **UIP-08 的目标函数写错了**：它优化平均延迟；在异步建议架构下，真正该优化的是**新鲜度命中率**（TTL 内到达的建议比例）与尾部公平性，而不是平均 RTT。→ 需要 UIP-13 的 freshness-aware batching。
- **UIP-03 的专家化缺少契约**：只有 adapter 路由，没有任务契约，就无法把「新任务」快速编译成可评测原型。→ 需要 UIP-15 的技能组合与 UIP-12 的契约编译器。

## 3. 瓶颈假设（可证伪）

- **H1（延迟结构）**：在真实云 RTT 分布下，同步云建议对 p99/标准差的抬升远大于对成功率的提升；异步 + TTL 门控能以零 critical-path 代价保留大部分步骤分收益。证伪方式：真实网络 trace 下，异步的步骤分收益 < 同步的 50%，或同步的 p99 抬升 < 20%。
- **H2（任务编译）**：手工为 32 任务写监视器不可持续；契约编译器能把「首次可评测时间」从数天压到 <1 天，并覆盖 ≥80% 的计分步。证伪方式：编译器生成的监视器在成功/失败回放上的 AUROC 中位数 <0.8。
- **H3（收益来源）**：当前阶段的边际分数主要来自**任务特定 wrapper / 步骤分安全网**，而非底座模型规模；快速原型的 ROI 高于再训一个更大的 VLA。证伪方式：在固定真机预算下，纯模型升级的分数增益超过契约 + 调度增益。
- **H4（评测预算）**：三阶段多保真 racing 能在 <50% 的「全量高保真」算力下，以 ≥95% 的概率选出与全量高保真相同的候选。证伪方式：代理与真机的秩相关 <0.5，或 racing 的晋级精确率显著低于全量高保真。

## 4. 本轮收敛：两个旗舰 + 一条共享契约

- **UIP-11 STRIDE（运行时的云边协同）**：云侧慢规划器/验证器发出带时间戳的**非阻塞建议**；边侧快策略继续执行；只在建议新鲜、置信足够、与当前观测一致时接管或塑形；高不确定时才有界地同步上云。核心承诺：**云延迟不进入每步 critical path**。
- **UIP-12 PROTOFORGE（迭代侧的快速原型场）**：把任务规格编译成「子目标图 + 可观测监视器 + 计分步权重 + 五轴扰动 + 多保真评分器」；用 racing 把算力和真机时段花在存活候选上；每次真机失败回流成新的便宜测试。
- **共享契约**：PROTOFORGE 编译出的监视器 `Φ_k`，既是本地 gate 的判据，也是云侧建议的子目标语言。**同一份契约，同时服务运行时和迭代**——这是本轮架构上的关键统一，避免了「离线评测一套、在线运行另一套」的双重维护。

**为什么这是当前最高杠杆**：它不碰电机/ROS/执行层，完全落在选手的 API 权限内；直接命中赛事两个最硬的约束——**逐步延迟可信度**与**真机时段稀缺**；且能复用公开的 32000 episodes 做冷启动。相比第 1 轮再加一个模型头，这两个基座改变的是「迭代速度」和「延迟结构」，属于乘数级收益。

## 6. 本轮最大风险

**一句话**：把云边异步当成免费午餐——当边缘策略本身很弱时，异步建议到达即过期，而 PROTOFORGE 的回放代理又可能高估其价值，最终在真机上同时损失成功率和步骤分。

## 1. 形式化与三条命题

### 1.1 符号

| 符号 | 含义 |
|---|---|
| `o_t` | 边缘时刻 `t` 的观测（4 路图 + 本体 + 语言） |
| `π_e, π_c` | 边缘快策略、云端慢规划器/验证器 |
| `m=(g,ã,τ,c,u,ttl)` | 一条云建议；`g` 子目标/技能，`ã` 可选动作先验，`τ` 云时间戳 |
| `Δ_t=t−τ` | 建议年龄 |
| `λ_t` | 门控变量（0/1） |
| `S(o_t)` | 局部安全集（关节限位、速度、碰撞、夹爪约束） |
| `Π_S` | 到安全集的投影 |
| `G(Δ)` | 年龄为 `Δ` 时使用建议的期望收益 |
| `κ` | 切换/塑形带来的风险成本 |
| `u_t` | 边缘不确定度（ensemble 分歧 / 验证器熵 / 新异度） |
| `C_k=(L_k,G_k,Φ_k,Ψ_k,S_k,Π_k)` | 第 `k` 个任务契约 |
| `F0..F3` | 保真层级：静态帧 / 开环回放 / 闭环回放 / 真机 |

### 1.2 建议与门控

\[
m=(g,\tilde a,\tau,c,u,\mathrm{ttl}),\qquad
\lambda_t=\mathbf 1[\Delta_t\le\mathrm{ttl}(g)]\,
\mathbf 1[c\ge c_{\min}]\,
\mathbf 1[d(m,o_t)\le\rho].
\]

\[
a_t=\Pi_{\mathcal S(o_t)}\!\left((1-\lambda_t)a_t^{e}+\lambda_t a_t^{m}\right).
\]

当 `m` 只提供子目标/技能而不提供连续动作时，`a_t^m` 解释为「由边侧技能策略在 `g` 条件下生成的动作块」，上式仍是塑形而非硬替换。

### 1.3 命题 1（非阻塞临界路径）

**命题**：若 `a_t` 的计算只依赖 `o_t`、历史与已到达的消息，且 `π_e`、`Π_S` 的耗时与云响应无关，则每步响应延迟的分布等于纯边缘系统；云 RTT 只改变 `λ_t`。

**证明**：由组合结构直接可得。`get_action` 的调用栈中不包含任何等待云响应的阻塞点；云消息由独立通道写入收件箱，`get_action` 只做一次非阻塞读取。故 critical path 上只有 `π_e`、`Π_S` 与常数级门控运算。∎

**工程含义**：同步云调用的延迟方差会直接叠加到响应分布；异步架构把「云慢」转化为「建议过期」，后者只损失收益，不制造延迟异常。这正是对赛事可信度检查的结构性防御。

### 1.4 命题 2（TTL 的前缀形状）

**命题**：若 `G(Δ)` 关于 `Δ` 非增、`κ` 为常数，则最优接受集合为前缀 `[0,τ*]`，`τ*=max{Δ:G(Δ)>κ}`。

**证明**：`{Δ:G(Δ)>κ}` 是非增函数的上水平集，必为区间；又因 `G` 非增，该区间从 0 开始。∎

**含义**：TTL 不是随意超参，而是「建议收益衰减曲线」与「切换风险」的交点。实践中用离线回放估计 `G(Δ)`，用真机/仿真估计 `κ`，再取保守分位数。

### 1.5 命题 3（选择性上云的阈值性）

**命题**：若云建议收益 `B(u)` 关于边缘不确定度 `u` 非减，等待成本 `c_d` 为常数，则存在阈值 `u*`，最优策略为「`u≥u*` 时同步上云，否则本地/异步」。

**证明**：净收益 `B(u)−c_d` 非减，故其符号最多改变一次；取 `u*=inf{u:B(u)≥c_d}` 即得阈值策略。∎

**含义**：不是所有决策都值得等云。把同步云限制在少数高不确定步骤，既保留关键收益，又把延迟风险局部化；`u*` 由 UIP-19 的校准器给出。

## 2. UIP-11 · STRIDE（云边异步建议）

### 2.1 架构

```text
                      ┌──────────────────────────────┐
                      │  Cloud worker (slow, heavy)  │
                      │  VLM verifier / planner      │
                      │  world-model rollout         │
                      │  skill router / memory       │
                      └──────────────▲───────────────┘
                                     │  advisories m=(g,ã,τ,c,u,ttl)
                                     │  (fire-and-forget, newest-wins)
   ┌──────────────┐   observation    │
   │ Robot / env  │◄──── actions ────┤
   └──────▲───────┘                  │
          │                 ┌────────┴─────────┐
          │                 │ EdgePort (per N)  │
          └─────────────────┤ fast π_e + gate  │
                            │ safety Π_S       │
                            │ chunk buffer     │
                            └──────────────────┘
```

- **边侧**：每个端口一个 `EdgePort`，维护动作块、子目标指针、收件箱、时钟、校准不确定度。`get_action` 永不等待云。
- **云侧**：无状态 worker 池 + 每端口会话缓存；接收快照与当前子目标请求，返回建议；允许批处理，但批处理只影响建议新鲜度，不影响控制回路。
- **协议**：请求带 `port_id, t, o_t, g_current, u_t`；响应带 `τ` 与 `ttl`；边侧 `newest-wins`，旧建议直接丢弃（不是排队）。
- **建议类型**：`g`（下一个子目标/技能）、`ã`（动作块先验/路点）、`c`（置信度）、`u`（云侧不确定度）、`ttl`（按子目标类型设定）。

### 2.2 边侧伪代码

```python
class EdgePort:
    def __init__(self, edge_policy, contract, cloud, k=8,
                 c_min=0.6, rho=0.35, sync_u=0.75, sync_timeout_ms=250):
        self.edge_policy = edge_policy
        self.contract = contract
        self.cloud = cloud
        self.k = k
        self.c_min, self.rho = c_min, rho
        self.sync_u, self.sync_timeout = sync_u, sync_timeout_ms
        self.buf, self.clock, self.subgoal = [], 0, 0
        self.inbox = NewestWins()

    def reset(self):
        self.buf, self.clock, self.subgoal = [], 0, 0
        self.inbox.clear()

    def get_action(self, obs):
        # 1) 必要时发起异步请求；绝不阻塞
        u = self.uncertainty(obs)
        if self._due(obs):
            self.cloud.submit(port_id=self.port_id, obs=snapshot(obs),
                              t=self.clock, g=self.subgoal, u=u)

        # 2) 高不确定 + 预算允许时，做有界同步上云（选择性 offload）
        if u >= self.sync_u and self._sync_budget_ok():
            m = self.cloud.request_sync(obs, self.subgoal,
                                        timeout_ms=self.sync_timeout)
        else:
            m = self.inbox.newest()

        lam = self.gate(m, obs)
        if not self.buf or self._replan(obs, m, lam):
            self.buf = list(self.edge_policy.get_action(obs)[: self.k])

        a_e = self.buf.pop(0)
        a = self.safe_project(a_e, obs)
        if lam and m is not None and m.action is not None:
            a = self.merge(a, m.action, obs)
            a = self.safe_project(a, obs)
        self.clock += 1
        return a

    def gate(self, m, obs):
        if m is None:
            return 0
        age = self.clock - m.tau
        return int(age <= m.ttl and m.c >= self.c_min and
                   self.consistency(m, obs) <= self.rho)

    def _replan(self, obs, m, lam):
        # 子目标完成/失败/强不一致才重规划；否则耗尽当前块
        return (lam and m.g != self.subgoal) or self.contract.failed(obs, self.subgoal)
```

### 2.4 与第 1 轮 UIP-01 的差异

| 维度 | UIP-01 RHPV-V | UIP-11 STRIDE |
|---|---|---|
| 验证器位置 | 边侧本地 VLM，同步 | 云侧慢验证器，异步建议 |
| 延迟影响 | 进入每步/chunk 临界路径 | 只影响建议新鲜度 |
| 重试 | 本地重试，可能发散 | 云建议 + 本地 gate，TTL 丢弃过期建议 |
| 多机 | 未定义 | N 端口收件箱 + 云侧会话隔离 |
| 失败模式 | 验证器延迟/误判 | 建议过期/不一致；有显式 fallback |

### 2.5 STRIDE 的失败模式与护栏

1. **建议全过期**：RTT > `ttl` 的比例高 → 退化为纯边缘。护栏：UIP-19 的 TTL 校准；若 TTL 命中率 <40%，改用选择性同步。
2. **建议与观测不一致**：一致性距离 `d>ρ` → 拒绝。护栏：视觉核验 + 几何检查 + 安全投影。
3. **边侧策略太弱**：异步建议即使准时也不足以救回 → 需要 UIP-14/15 的检索/技能库补强，或提高同步上云比例。
4. **N 端口资源竞争**：云队列拥塞导致建议延迟 → UIP-13 的 freshness-aware 调度；异步架构下只损失新鲜度，不造成控制回路卡顿。
5. **动作统计异常**：建议接管造成动作跳变 → UIP-18 的平滑投影/速率限制；必要时应拒绝而非硬切。

```python
def compile_contract(task_card, dataset, manual_excerpt):
    # 1) LLM 起草子目标图与监视器（不直接信任）
    draft = llm_draft(task_card, manual_excerpt)

    # 2) 从数据集构造弱标注：成功 episode vs 失败/截断 episode
    episodes = load_episodes(dataset, task_card.name)
    labels = label_success(episodes)          # 成功/失败/不确定

    # 3) 在回放帧上验证每个监视器
    for phi in draft.monitors:
        scores = [phi(frame) for frame in sample_frames(episodes)]
        tpr, tnr, auroc = discrimination(scores, labels)
        if auroc < 0.80 or tpr < 0.70 or tnr < 0.70:
            draft.revise(phi)                  # 让 LLM 改写谓词/阈值
        if phi.is_safety_critical:
            require_human_review(phi)

    # 4) 编译为可执行监视器 + 扰动配置 + 代理评分器
    monitors = codegen_monitors(draft)
    perturbations = instantiate_axes(draft.perturbations, dataset)
    scorer = ProxyScorer(draft.scoring_steps, monitors)
    contract = Contract(task_card, draft.graph, monitors,
                        draft.scoring_steps, perturbations, scorer)
```

### 3.3 多保真阶梯

| 层级 | 做什么 | 典型成本 | 能杀掉什么 | 不能证明什么 |
|---|---|---|---|---|
| F0 静态帧单测 | 每个监视器在成功/失败帧上的判别力 | 秒–分钟 | 谓词不可观测、阈值错 | 动作质量、闭环稳定性 |
| F1 开环回放 | 在留出 episode 上算动作块误差/似然、监视器覆盖率 | 分钟–小时 | 明显错误的适配器/提示词 | 分布偏移下的闭环恢复 |
| F2 闭环回放 | 数据集初始化 + 学习动力学/仿真，跑完整任务 | 小时 | 大多数闭环失败、超时、重试发散 | 真机接触/摩擦/视觉差异 |
| F3 真机 | 官方评测或自建真机时段 | 天/时段 | 真实泛化与可信度 | 统计显著性需重复 |

### 3.4 多保真 racing

```python
def protoforge(candidates, contract, budget):
    alive = candidates[:]
    for level in [F0, F1, F2, F3]:
        results = evaluate(alive, level, contract)
        alive = promote_top_half(alive, results, min_keep=1)
        budget -= cost(level) * len(alive)
        if budget <= 0:
            break
    return best_by_paired_bootstrap(alive)
```

**统计纪律**：同一候选在各级别使用配对种子；晋级比较用配对 bootstrap/置信区间，而不是单点均值；F3 只用于最终少数候选；所有负结果写入 UIP-20 账本。

### 3.5 代理与真机的对齐

PROTOFORGE 的核心风险不是「跑得慢」，而是「跑得快但方向错」。因此必须报告：
- **监视器判别力**：AUROC / TPR / TNR；
- **代理-真机秩相关**：Spearman `ρ(J_proxy, J_real)`；
- **晋级精确率**：被晋级候选在真机上真正优于现任的比例；
- **校准误差**：代理分数与实际步骤分的 ECE。

若 `ρ<0.5`，racing 不可信，应退回「少候选 + 高保真」而非继续加速。

## 4. 其余点（UIP-13~20）

**UIP-13 FAB（Freshness-Aware Batching）**｜动机：异步架构下，云侧目标不是最小化平均 RTT，而是最大化 TTL 内送达的建议数，并保证 N 端口公平。机制：每个请求带 TTL deadline，调度器用 age-aware EDF（最早 deadline 优先）+ 有界批处理 + per-port KV 缓存；批大小设上限以避免尾部放大；拥塞时优先丢弃已过期请求。指标：TTL 命中率、每端口 p95 建议年龄、建议吞吐、公平性（Jain 指数）。风险：批处理虽不阻塞控制，但会降低新鲜度；需在 FAB 中显式权衡。**这是 UIP-08 的目标函数修正。**

**UIP-14 CAM（Cloud Associative Memory）**｜动机：32k episodes / 169 小时是现成的「云端情景记忆」，不训练也能提供动作先验。机制：云端对每个 episode 建视觉-语言-本体联合嵌入索引；边侧异步发送查询，取回 top-k 相似片段（含动作块/技能标签），作为 `ã` 注入 STRIDE；用一致性门控防止跨任务误检索。可行性：高（ANN 检索 + 预计算嵌入）；成本：索引存储与查询延迟；风险：相似不等于可执行，需 UIP-18 安全投影与任务过滤。**与 UIP-01 的差异：不是学一个验证器，而是检索真实演示。**

**UIP-15 SKILL-MESH（云端技能库 + 契约组合）**｜动机：32 个任务共享大量原子技能（抓、放、插、倒、折、拉链、拧）。机制：从数据中切分/聚类出短时技能 `s=(π_s,pre_s,post_s,termination)`；任务契约 `G_k` 的每个子目标绑定一个技能；运行时由 STRIDE 选择技能并组合；新任务只需写契约，不必重训整模型。指标：技能复用率、组合成功率、新任务 TTC。风险：技能边界/前置条件错误会级联；用监视器 `Φ_k` 做入口/出口校验。**与 UIP-03 的差异：不是任务级 LoRA 路由，而是子目标级技能复用。**

**UIP-16 CF-REPAIR（Counterfactual Repair Data）**｜动机：真机失败是最贵的信号，应转成定向训练数据。机制：对失败片段做反事实编辑（物体位姿/夹爪状态/背景/干扰物），用世界模型或图像编辑生成「本应成功」的短轨迹；先用 F0/F1 过滤，再进训练/检索库。指标：失败模式覆盖率、定向修复后的子目标成功率。风险：合成分布偏移；只用于补短板，不替代真实数据。

**UIP-17 SHADOW-TWIN（云侧影子诊断）**｜动机：真机时段不能反复试，但可以在评测时「顺带」做诊断。机制：把观测镜像到云侧，运行多个验证器/策略/世界模型，只产出诊断与建议，不回传动作；用于赛后归因和下一轮候选生成。约束：不得影响主控制回路；需明确资源隔离与隐私/规则合规。指标：诊断覆盖的失败模式比例、对下一轮提升的预测力。风险：资源竞争可能拖慢云建议；默认降优先级。

**UIP-18 SAFE-PROJ（安全投影与拒止）**｜动机：云建议再聪明，也不能突破局部安全。机制：对任何建议动作先做关节限位/速度/碰撞/夹爪约束投影；若投影距离超过 `δ` 或需要大幅修改，则拒绝建议并回退本地；对技能切换加速度/姿态平滑。指标：越界拒绝率、动作跳变（jerk）分位数、回退后的任务成功率。风险：过度保守会拒绝有用建议；`δ` 需按任务校准。

**UIP-19 UQ-GATE（校准不确定度）**｜动机：选择性上云、重试、弃权都需要可信的 `u_t`。机制：ensemble 分歧 + 验证器熵 + 新异度（相对训练分布的距离）+ conformal 校准；输出校准后的风险分数而非原始 softmax。用于：`u_t≥u*` 时同步上云；`c< c_min` 时不重试；高不确定且无云时优先保步骤分。指标：ECE、风险-覆盖曲线、误判重试率。风险：校准集与真机分布不一致；需在线监控漂移。

**UIP-20 PROTO-LEDGER（实验账本）**｜动机：快速原型最容易产生「跑了很多但不知道什么有用」的幻觉。机制：每次实验记录代码/契约/种子/成本/代理与真机结果；强制配对种子与消融；显式记录负结果与 kill 理由；按「每单位真机时段带来的分数增益」排序。指标：实验可复现率、负结果复用率、成本-收益比。风险：流程负担；用模板与自动记录降低摩擦。

## 5. 实验设计 E007–E014 与首轮合成结果

> **纪律**：E007/E009 是**合成机制检验**，只回答「机制是否存在/方向是否正确」，不回答「在 UniBot 上能涨多少分」。真实收益必须用官方 API + 真机时段校准。

### E007 · STRIDE vs 本地 vs 同步（已运行）

脚本：`exp/stride_cloud_edge_sim.py`；结果：`exp/stride_cloud_edge_results.json`。
设置：32 任务 × 80 episodes；每任务 4–8 个子任务；边缘步延迟 lognormal(25ms, cv=0.2)；云 RTT lognormal(median 0.9s, σ=0.38)+0.08s；子任务时长 ~2s；episode 预算 = 1.55×名义边缘时长；TTL=1.6s。同步=每个子任务起点阻塞；异步=不阻塞、按到达年龄折损收益；选择性=只在低于中位难度的子任务上同步（oracle 上界）。

| 模式 | 成功率 | 平均步骤分 | 超时率 | 平均同步等待 | p50 | p95 | p99 | 延迟标准差 | 透明排序代理 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| local | 0.112 | 31.1 | 0.000 | 0.00s | 25.0ms | 34.7ms | 39.8ms | 5.2ms | 33.3 |
| **async** | **0.181** | 39.9 | **0.000** | **0.00s** | **25.0ms** | **34.7ms** | **39.8ms** | **5.1ms** | 43.5 |
| selective (oracle) | 0.149 | **41.5** | 0.098 | 1.47s | 25.0ms | 35.2ms | 43.2ms | 92.6ms | **44.5** |
| sync | 0.016 | 43.0 | **0.362** | 3.79s | 25.1ms | 36.0ms | **924.7ms** | **143.3ms** | 43.3 |

**读法**：
1. 异步的延迟分布与本地**逐位相同**（p50/p95/p99/std 几乎不变），但成功率 0.112→0.181、步骤分 31.1→39.9；这是「云收益、零延迟税」的机制证据。
2. 同步把步骤分抬到 43.0，但成功率塌到 0.016、超时率 36.2%、p99 924.7ms、标准差 143.3ms——正是可信度检查最敏感的结构。它多出的 3.1 步骤分（相对异步）**不值得** 36% 的超时与 28× 的延迟标准差。
3. 选择性（oracle 上界）给出更高步骤分 41.5，但仍有 9.8% 超时、p99 43.2ms、std 92.6ms；真实系统必须用 UIP-19 的校准不确定度替代 oracle，且给同步调用硬超时。
4. **透明排序代理** `步骤分 + 20×成功率` 只是为了让不同模式可排序；官方权重未知，不能当作榜单预测。异步与同步在该代理上接近，但异步的尾部/超时结构明显更干净。

**局限**：参数未拟合真实服务；子任务成功模型是 Bernoulli；超时即截断；云建议收益与年龄的折损是线性假设。真实结论必须在官方 API 上采集 RTT/超时/动作分布后重跑。

### E008 · 选择性上云的阈值曲线（计划）

- 变量：`u*` ∈ {0.5,0.6,0.7,0.8,0.9}；同步硬超时 ∈ {100,200,400}ms；网络档位 {好, 典型, 差}。
- 指标：综合分、超时率、p99、TTL 命中率、每 episode 同步次数。
- 假设：存在内点 `u*` 使综合分高于全异步与全同步；差网络下最优 `u*` 上移（更少同步）。
- 证伪：若所有网络档位下阈值策略都不优于全异步，则 STRIDE 简化为纯异步 + UQ-GATE。

### E009 · PROTOFORGE 多保真 racing（已运行）

脚本：`exp/protoforge_racing_sim.py`；结果：`exp/protoforge_racing_results.json`。
设置：K=24 候选；真实效用 `θ~N(0,1)`；保真噪声 σ={0.90,0.45,0.16}；成本={1,4,16}；4000 次重复。

| 策略 | P(选中真实最优) | 平均后悔 | 平均成本 | 相对全量高保真成本 |
|---|---:|---:|---:|---:|
| uniform-low | 0.374 | 0.499 | 24 | 6.3% |
| uniform-mid | 0.596 | 0.172 | 96 | 25.0% |
| uniform-high | 0.833 | 0.024 | 384 | 100% |
| two-stage | 0.594 | 0.171 | 72 | 18.8% |
| **three-stage** | **0.812** | **0.032** | **168** | **43.8%** |

**读法**：
1. 三阶段 racing 以 43.8% 的成本拿到全量高保真 97.5% 的「选中真实最优」概率（0.812 vs 0.833），后悔仅从 0.024 升到 0.032。
2. 两阶段不够：低保真噪声太大（σ=0.90），直接把一半候选筛掉会误杀真优；**至少需要一次中保真筛选**。
3. 这为 PROTOFORGE 的阶梯设计提供了机制证据：F1/F2 不是可选项，而是 racing 可信的前提。
4. **局限**：真实任务中不同保真层的相关性/偏差不是同方差高斯；必须用 UIP-20 记录代理-真机秩相关，低于 0.5 时退回少候选高保真。

### E010 · 契约编译器的监视器判别力（计划）

- 取 6 个高价值任务（HangCup、PlugCharger、FoldTowel、PourOutMedicine、DisconnectEthernet、OrganizeBookshelf）。
- 人工写 3–6 个监视器作对照；编译器生成同数监视器；在成功/失败回放上比较 AUROC/TPR/TNR。
- 目标：中位 AUROC ≥0.85，≥80% 计分步可观测；若 <0.8，则 PROTOFORGE 只用于辅助而非自动晋级。

### E011 · CAM 检索式先验（计划）

- 指标：top-k 检索的任务内/跨任务准确率、检索延迟、动作先验对 F1 误差的降低、STRIDE 接管后的真机代理收益。
- 关键对照：随机片段 vs 视觉检索 vs 视觉+语言+本体检索。
- 风险：跨任务误检索；用任务过滤器与一致性门控。

### E012 · SKILL-MESH 组合（计划）

- 从 32 任务中切分原子技能，构建技能库；在留出任务上只写契约、不训新策略。
- 指标：组合成功率、技能复用率、新任务 TTC、失败归因（前置/执行/后置）。
- 对照：任务级 LoRA 专家（UIP-03）。

### E013 · SHADOW-TWIN 诊断（计划）

- 在真实/回放评测中镜像观测，运行多个验证器；比较诊断标签与人工赛后归因的一致性。
- 指标：失败模式覆盖率、诊断延迟、对下一轮改进的预测力。
- 约束：资源隔离；默认最低优先级；不影响主建议。

### E014 · 端到端（计划）

- 组合 STRIDE + PROTOFORGE + SKILL-MESH + FAB；在离线代理上做 2×2 消融（有无异步、有无 racing）。
- 目标：不是追求一个漂亮的单一数字，而是验证「延迟结构不变 + 迭代次数增加 + 步骤分提升」三者同时成立。
- 预注册假设：异步带来的 p99 变化 <5%；racing 使同等真机预算下的候选数 ×2；步骤分提升 ≥5 分（代理）。

## 6. 资源、时间线与 kill 标准

### 6.1 时间线（8 周，粗排）

- **第 1 周**：为 6 个高价值任务写契约；搭 F0/F1；实现 `EdgePort` + 假云（固定延迟/抖动）做压力测试。
- **第 2 周**：F2 闭环回放；估计 `G(Δ)` 与 TTL；UIP-19 的校准器初版；E007 真实 RTT trace 重跑。
- **第 3–4 周**：云 worker（VLM 验证器/世界模型）；FAB 调度；CAM 检索；离线 A/B。
- **第 5–6 周**：预约真机时段；用 PROTOFORGE 晋级；校准代理-真机相关性；记录失败回流。
- **第 7–8 周**：SKILL-MESH/CF-REPAIR；端到端消融；形成提测版本。

### 6.2 资源

- 本地/云 GPU：1–2 张推理卡跑边侧小模型与 F2；云侧 worker 按需；无需额外购买真机。
- 数据：公开 32 数据集；不假设能拿到官方评测帧之外的私有数据。
- 人力：1 人可完成最小闭环；契约编译器与 racing 是自动化的重点。

### 6.3 Kill 标准（提前写死，避免自欺）

1. **TTL 命中率 <40%**（真实 RTT）→ STRIDE 的异步收益不足，转选择性同步或纯本地。
2. **同步 p99 > 2× 边缘 p99 且超时率 >5%** → 禁止无硬超时的同步云调用。
3. **监视器中位 AUROC <0.8** → PROTOFORGE 不自动晋级，退回人工监视器 + 少候选。
4. **代理-真机 Spearman <0.5** → racing 不可信，改用少候选 + 高保真。
5. **选择性上云在所有网络档位都不优于全异步** → 砍掉同步分支，简化系统。

## 7. 本轮最大风险

**一句话**：把云边异步当成免费午餐——当边缘策略本身很弱时，异步建议到达即过期，而 PROTOFORGE 的回放代理又可能高估其价值，最终在真机上同时损失成功率和步骤分。
