# 第 8 轮 · DOPL：终局放置是扩散先验，10 次试次是在线校准，通用操作是物体中心

> 检索/复核日期：2026-10-25（UTC）。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮灵感词是「扩散策略」「在线学习」「通用操作」。我先做了一次不客气的核实：**公开榜单仍是占位数据，“榜首 29.7%”不是真实成绩；真正的新事实是规则手册——排名先比平均成功率，步骤分只在同分时比较；每任务 10 次 = 5 类泛化 ×2；单次 180 秒；单模型、架构不限、自部署。** 这三个事实把上一轮“终局放置 + 步骤分大头”的判断修正为“终局放置 + 成功率优先 + 步骤分只做诊断”。然后我把三个灵感词各自“去魅”：扩散策略不是“把动作头换成 diffusion”（WLA-1.0 本身就是 MMDiT），在线学习不是“评测中跑 PPO”（没有奖励、没有 G1、样本太少），通用操作不是“再训一个更大的通才”（底座已经是 6B 通才）。真正的增量在：**用扩散建模终局放置的多模态 SE(3) 分布，用成功评论家选样本，用每任务 10 次试次的自监督结果在线校准评论家/记忆，用物体中心表示把放置先验跨 32 任务共享。**

## 0. 本轮先核实：五个会改变策略的事实

### 0.1 排名规则：成功率优先，步骤分只是同分裁决

规则手册（中英文两版）原文：

> “实时榜单按 32 个任务的总平均成功率进行排序，成功率相同时按总平均步骤分排序，若仍相同，则提交日期较早的模型排序靠前。”[S6][S7]

这修正了第 7 轮“成功率与步骤分综合排序”的模糊理解。**步骤分不是第二目标，而是零权重的同分裁决**。这意味着：

- 一个任务做完 90% 步骤但终局失败，成功率为 0；另一个任务 100% 完成，成功率为 1。**最后 10% 的价值远大于前 90% 的边际改进**。
- “终局步骤占 39.8% 步骤分”仍然说明终局是成功闸门，但不能再拿“步骤分大头”论证资源分配；正确的论证是“终局是 32/32 任务的通关闸门，且跨 5 轴同时起作用”。
- 步骤分的新用途是**诊断**：`gap = 步骤分 − 成功率`。gap 大 = 模型能走到后段但倒在最后一公里；gap 小 = 早期感知/抓取就失败。它是 X 光片，不是记分牌。

### 0.2 每任务 10 次 = 5 类泛化 ×2，单次 180 秒

规则原文：

> “每个任务执行 10 次独立运行……10 次运行中包含以下 5 种泛化类型，每种类型各出现 2 次：位置泛化、干扰物泛化、桌面背景泛化、未见物品泛化、人为干扰泛化。”[S6][S7]

> “每个任务单次真机执行最大允许执行时间为 180 秒，超时记为失败。”[S6][S7]

这给出三个硬约束：

- **每个任务、每个泛化轴都是等权的**：任务占 1/32，轴占该任务的 1/5（即全局 1/160），单次试次占全局 1/320。没有“高权重任务”可押。
- **每个任务只有 2 次/轴**：方差极大。一个轴的两次都失败，该轴就是 0；三次成功可能只是运气。必须用配对/bootstrap，而不是看单次涨跌。
- **180 秒足够做一次“最后 3 厘米”的闭环**：演示中位数约 6–10 秒，终局 DPP/OSC/SVL 花 1–3 秒完全在预算内；但长程任务（T16/T17/T31）要限制重试次数。

### 0.3 公开榜单仍是占位，29.7% 不是真实头部

本轮实测：

- `leaderboard.html` 底部仍写“即将发布 Coming Soon”[S2]。
- `leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，8 个模型、256 条 task_metrics，平均成功率 20.5%–29.7%[S3]。
- 详情页视频明确写“测试视频占位，后续可替换为真实视频文件”[S4]。
- `runs.html` 仍是 `256 / 256` 占位记录[S4]。

所以：**“榜首 29.7%”是占位样例，不是真实队伍成绩；不能据此分析“头部方案”或推断轴级瓶颈。** 但 29.7% 与公开的真实世界泛化数字量级一致：MolmoAct2 在 MolmoBot 上 20.6%（π0.5 为 10.3%）[S29]，Wall-OSS-0.5 零样本任务进度 51.1%（不是成功率）[S30]，DreamZero 报告 2× 泛化但 14B、7Hz[S28]。因此我把“≈30% 天花板”当作**工作假设**，而不是已核实榜单事实。

### 0.4 数据与接口：33,276 条，v2 接口支持四路相机 + EE 6D

- HF collection 的 32 个数据集合计 **33,276 条 episode**；HangCup 1,043 条、194,564 帧、30fps；全部 `lastModified` 集中在 **2026-10-14**[S9]。
- 四路相机：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`，480×640；EE 位姿为 base 系 `xyz(3)+rpy(3)`[S10]。
- 提交接口 v2：`control_space` 为 `joint` 或 `ee`（互斥）；`obs_delta_indices` 决定“传哪些键 + 每键堆叠几帧”；`image_resize` 自定；`action_chunk_size` 自定；`reset()` 每 episode 一次；`observation.language` 是整段不变的单个字符串[S10]。
- **接口没有“在线学习”字段，也没有禁止**。这是本轮需要发邮件确认的合规边界：允许冻结模型 + 上下文适配，还是允许评测流内更新小头/记忆？[S10]

### 0.5 32 任务的结构没有变，但“最后一步”的类型值得重排

32 个任务仍是 12 Easy / 12 Medium / 8 Hard，2–5 步，满分 100；终局步骤合计 1275/3200 = 39.8%，放置/插入/堆叠/闭合/倾倒类步骤约 59.7%（关键词粗分类）[S8]。终局动作可分成六类：

| 终局类型 | 代表任务 | 成功所需的关键能力 | 主要失败模式 |
|---|---|---|---|
| 放置/挂 | T01、T02、T03、T08、T15、T21、T24、T25、T30 | 目标槽位 grounding、释放高度 | 放偏、掉落、没挂住 |
| 插入/插拔 | T05、T10、T13、T26 | 6D 对准、力/深度、柔顺 | 插不进、只进一半、拔不出 |
| 堆叠 | T20、T27 | 相对位姿、平整度、稳定性 | 叠歪、滑落 |
| 闭合/锁/拉链 | T09、T17、T18、T19、T23、T28、T29、T31 | 接触-rich 操作、末端轨迹 | 没合上、拉链卡住、锁没扣 |
| 倾倒/抽取 | T11、T14、T32 | 抓取姿态、流量控制、目标容器 | 倒歪、倒多/倒少、挑错 |
| 折叠/摆放 | T07、T16 | 布料/铰链操作、形状控制 | 没摆正、折痕不对 |

**共性**：32 个终局里 28 个是“把物体放到/送入某个目标关系”，4 个是“拔出/取出/翻转/倾倒”；它们的前置步骤也大量包含放置。**终局不是“动作结束”，而是“关系成立”**。这决定了我们应该预测“关系位姿”，而不是“动作轨迹”。

## 1. 三个灵感词：先去魅，再落地

### 1.1 扩散策略：不是换动作头，是换“建模对象”

WLA-1.0 本身就是 6B、UnifoLM-ER-1 4B + **MMDiT action expert**，训练约 2,500 小时、64 个任务，Apache-2.0[S11]。所以“用 diffusion policy”在 UniBot 里没有增量；增量在**把扩散用在哪里**：

- 动作头 diffusion 解决的是“单步/短程动作的多模态”，但 32 个任务的失败大量发生在**终局关系位姿**：叠碗是叠在碗 1 还是碗 2？插头是插第一个孔还是第二个？相框是立在支架上还是平放？这些是**任务空间的离散/多峰选择**，不是关节空间的抖动。
- 把终局放置建模成**物体中心 SE(3) 分布**，扩散模型可以同时表达“放在这里/那里”“正着/斜着”“先放再推/直接放”的多模态；中位数回归会把多个模态平均成一个不存在的位姿。
- 证据链：Diffusion Policy 在多模态动作上平均提升 46.9%[S12]；SPOT 用物体中心 SE(3) 位姿轨迹扩散，解耦 embodiment 与感知[S13]；AnySlot 用生成式视觉目标做零样本槽位放置，真机 82%[S14]；SpaceVLA 用显式抓/放锚点把放置误差降到 0.7cm[S15]；Spa-Bench 指出 OOD 空间 grounding 是真机主要瓶颈（ID 67.5–73.3% → OOD 40.7–52.0%）[S16]。

**本轮的定义**：DPP（Diffusion Placement Prior）不是“又一个 diffusion policy”，而是**以检索到的演示放置位姿为均值、以物体/容器几何为条件、以 SE(3) 残差为变量的扩散先验**；它输出 K 个候选，交给评论家选，而不是直接执行均值。

### 1.2 在线学习：不是在线 RL，是“上下文适配 + 非参数记忆 + 评论家校准”

UniBot 的约束让在线 RL/DAgger 基本不可行：

- 评测期没有奖励，只有最终成功/失败；每任务 10 次，样本极少。
- 选手不一定有 G1；官方只提供远程 API，不提供本地真机。
- 规则要求“稳定的在线推理”，但没有说允许评测流内更新权重[S6][S7]。

所以“在线学习”应该拆成三层，按合规风险从低到高：

1. **OCA（Online Context Adapter）**：用最近 N 帧、proprio、历史动作编码成 context token，通过 AdaLN 调制动作专家/DPP；**不更新权重**，只更新每 episode 的上下文。Self-Adaptive VLA 用同类 context token 在硬件偏移下恢复 >80% 性能[S22]；RoboTTT 用 test-time training 的 fast weights 做到 8K 时间步上下文、on-the-fly 策略改进[S20]；TTT-RM 把 TTT 当残差记忆[S21]；TEMPO 用冻结 critic + 熵正则 + 记忆做无奖励 TTA[S23]。
2. **OML（Online Memory of trial outcomes）**：每任务维护一个小记忆库，存终局位姿、视觉嵌入、成功/失败、步骤；用 kNN/逻辑校准修正评论家。**不训练基座**，只在任务内累积；任务结束清空，避免跨任务泄漏。
3. **OSC 校准（Online Success Critic calibration）**：评论家输出成功概率，用试次结果做温度/最后一层校准；这是“在线学习”的最安全形态，且直接服务成功率优先的排名。

**激进的 TTT fast weights**（在动作专家里加可在线更新的小矩阵）作为研究轨道，只有在官方书面确认允许后才进计分跑；默认不进主路径。

### 1.3 通用操作：不是更大模型，是“物体中心 + 技能条件”

底座已经是 6B 通才，32 个任务也不是“任务数量不够”；真正的通用性缺口是：

- **物体中心**：同一套“抓-搬到-放到目标关系”的技能，应该在杯子、碗、盘子、工具、盒子、拉链之间共享；用 `T_R^O`（物体在目标容器/表面坐标系下的位姿）表示，而不是用绝对世界坐标。
- **技能条件**：32 个任务可以分解成 8 类技能（grasp / transport / place / insert / stack / close / pour / fold）。用技能 embedding 条件化一个共享的 DPP/动作专家，而不是 32 个任务头。
- **双手关系**：T05/T10/T26/T28/T30 等任务里，容器可能被一只手拿着；此时目标坐标系不是桌面，而是**被持容器/端口的腕部坐标系**。DPP 必须支持“容器在手”的相对位姿，否则插头/网线任务会系统性失败。

证据：SPOT 的物体中心 SE(3) 扩散[S13]；SDP 的技能条件 diffusion + 轻量 router[S34]；RouteRLT 用 phase selector 在通用 VLA 与精度专家之间切换，证明“何时切换”本身是问题[S26]；Wall-OSS-0.5 的 MoT 多模态混合[S30]。我们的做法不是再加一个 14B WMA，而是**在最后一段用物体中心扩散 + 评论家**，把“通用”落在表示和技能上。

## 2. 主判断：从“中位数放置”升级为“扩散放置 + 在线评论家”

### 2.1 排名算术：终局仍是最大杠杆，但“最差任务”同样重要

设任务 t 的成功率为 `S_t`，轴 a 的成功率为 `S_{t,a}`：

```text
L = (1/32) Σ_t S_t = (1/160) Σ_{t,a} S_{t,a}
S_t = (1/10) Σ_{a=1..5} Σ_{r=1..2} 1[success_{t,a,r}]
```

于是：

- 单个任务从 0 → 30%：`+0.30/32 = +0.94pp` 全局。
- 单个轴在 32 个任务上平均 +10pp：`+0.10/5 = +2.0pp`。
- 终局放置在所有任务上 +10pp，若到达终局的概率 `q≈0.6`：`+0.10×0.6 = +6.0pp`。
- 最差 6 个任务从 0 → 30%：`6×0.94 = +5.6pp`。
- 步骤分 +10：**只有在成功率完全同分时才可能改变排名**，期望权重接近 0。

**结论**：终局放置仍是最大杠杆（约 3 倍于单轴），但“最差任务组合”几乎同样大，且风险更低。资源分配建议：**60% 终局放置（DPP/OSC/SVL），25% 最差任务（portfolio + 调试槽），15% 轴级鲁棒（OCA/NRB）**。

### 2.2 步骤分作为 X 光片，而不是记分牌

```text
gap_t = step_score_t − success_rate_t
```

- `gap_t > 15pp`：模型能完成大部分步骤，倒在终局 → 投 DPP/OSC/SVL。
- `gap_t < 5pp`：早期就失败 → 投感知/抓取/SSG/检索。
- 两者都低：任务本身难或数据少 → 投数据/调试槽，不要盲目加终局模块。

第 7 轮的占位数据显示 8 个模型平均 `步骤分−成功率 ≈ +8.6pp`，但这仍是占位数据，不能当真实证据[S3]。真实榜单/调试槽出来后，这张表才是资源分配的依据。

### 2.3 为什么这比 PILOT 更锋利

| 维度 | 第 7 轮 PILOT | 本轮 DOPL |
|---|---|---|
| 排名目标 | 成功率 + 步骤分综合（模糊） | 成功率优先，步骤分只做诊断/同分 |
| 放置表示 | K 条演示的中位数位姿（单峰） | 物体中心 SE(3) 扩散（多峰）+ 检索先验 |
| 终局验证 | 手写谓词 + 稳定性 | 学习型成功评论家 + 在线校准 |
| 检索 | 静态 ICR 库 | ICR+ + 每任务 OML 记忆 |
| 在线 | 无 | OCA 上下文适配 + OML + OSC 校准（默认不更新基座） |
| 通用 | 32 任务共享一个 checkpoint | 物体中心 + 技能条件 + 双手容器坐标系 |
| 工程 | FLEET 第六轴 | 降为检查单；研究火力集中在终局 |

## 3. 方案轮廓：DOPL-GPR

```text
language（160 条复述之一）+ 4 路相机 + proprio
        │
        ▼
SSG+：官方评分步骤图 → 当前步骤 s、成功谓词、撤销转移
        │
        ├─ OCA：最近 N 帧/proprio/动作 → context token z_t → AdaLN
        │
        ├─ 感知：物体/容器 mask、6D 位姿、点云；容器可能在手
        │
        ├─ 若 s 是终局放置/插入/堆叠/闭合/倾倒：
        │     ICR+ 检索 K 条演示 → μ, Σ（容器系释放位姿）
        │     DPP：采样 δ ~ p_θ(δ | l, skill, P_O, P_R, X_0, μ, Σ)
        │           X_i = μ ⊕ δ_i，投影成 2D 锚点
        │     OSC：对 X_i 打分（成功概率 + 短程后果）→ X*
        │     SVL+：伺服 → 缓放 → 稳定/谓词校验 → nudge/regrasp/retry
        │
        └─ 否则：
              WLA-1.0 / GPR-VLA action expert → action chunk
        │
        ▼
OML：记录 (task, step, X*, embedding, outcome) → 评论家校准 + 检索记忆
        │
        ▼
NRB：官方 human 备注剧本（先叠后撤/拉链拉开/拧回瓶盖…）→ 恢复训练
```

一句话：**把公开评分步骤当骨架，把 33k 演示当终局位姿库，把扩散当多峰提议器，把评论家当成功率守门员，把 10 次试次当在线校准流。**

## 4. 与上一轮的关系：保留、升级、修剪

**保留**：WLA-1.0-Base / GPR-VLA 主干；SSG 的步骤图；ICR 的检索思想；SVL 的“缓放 + 验证 + 重试”；NRB 的官方备注恢复；L2L 数据协议；DebugLoop；AH-TP/Endurance/Compliance。

**升级**：
- OPT 中位数 → **DPP 扩散先验**。
- PGL 手写锚点阶梯 → **DPP 采样 + 2D 投影**。
- SVL 手写谓词 → **OSC 学习型评论家 + 在线校准**。
- ICR 静态库 → **ICR+ + OML 每任务记忆**。
- “步骤分大头” → **成功率优先 + 步骤分诊断**。
- “补最弱轴” → **终局 + 最差任务组合**。

**修剪**：把步骤分当第二目标；全 32 任务高保真孪生；自由仿真数据；运行时仿真/MPC；仿真 RL；每任务 LoRA/模型合并；WMA-0 进主路径；FLEET“第六轴”。

## 5. 风险与合规（先立后破）

- **规则未写在线学习**：默认只做“冻结基座 + 上下文/记忆/最后一层校准”；TTT fast weights 只在书面确认后启用；提供 frozen 审计模式。
- **单模型审计**：DPP/OSC/OCA 都是同一个 checkpoint 的模块；OML 是数据不是模型；模型卡逐项披露。
- **透明/布料/小件**：6D 位姿和评论家都可能失效；分桶回退到 PGL/OPT/VLA，不在这些任务上硬上 DPP。
- **延迟**：K=8、4 步扩散、8 次评论家前向不能拖垮 30Hz 控制；用蒸馏/缓存/只在终局调用；p99 超预算就降 K 或回退。
- **评论家过自信**：集成 + 温度校准 + 硬负样本；`p<0.5` 时不选，退回 VLA。
- **在线记忆污染**：每任务 cap 64、任务结束清空、不跨任务；失败样本也进负库。
- **占位榜单**：不拿 29.7% 推断真实强弱；真实榜单出来后重跑 `gap` 诊断。
- **统计噪声**：320 次试次、p≈0.3、SE≈2.56pp；用配对/bootstrap，至少 +3pp 才宣称有效。

## 6. 一句话押注

**把终局放置从“中位数位姿”升级为“物体中心扩散先验 + 在线校准的成功评论家”：扩散负责多峰提议，评论家负责成功率守门，每任务 10 次试次的自监督结果负责在线校准，物体中心表示负责跨 32 任务共享——这是成功率优先规则下最值得押注的方向。**

## 1. 事实核对（2026-10-25）

### 1.1 排名规则：成功率优先，步骤分只是同分裁决

规则手册中英文两版原文：

> “实时榜单按 32 个任务的 **总平均成功率** 进行排序，成功率相同时按 **总平均步骤分** 排序，若仍相同，则提交日期较早的模型排序靠前。”[S6][S7]

这条规则把第 7 轮“成功率与步骤分综合排序”的模糊理解修正为：

- **步骤分不是第二目标，而是零权重的同分裁决**；只有在成功率完全相同时才可能改变排名。
- 一个任务做完 90% 步骤但终局失败，成功率为 0；另一个任务 100% 完成，成功率为 1。**最后 10% 的价值远大于前 90% 的边际改进**。
- 步骤分的新用途是**诊断**：`gap_t = step_score_t − success_rate_t`。gap 大 = 能走到后段但倒在最后一公里；gap 小 = 早期感知/抓取就失败。它是 X 光片，不是记分牌。

### 1.2 每任务 10 次 = 5 类泛化 ×2，单次 180 秒

规则原文：

> “每个任务执行 10 次独立运行……10 次运行中包含以下 5 种泛化类型，每种类型各出现 2 次：位置泛化、干扰物泛化、桌面背景泛化、未见物品泛化、人为干扰泛化。”[S6][S7]

> “每个任务单次真机执行最大允许执行时间为 180 秒，超时记为失败，并根据执行情况计算步骤分。”[S6][S7]

三个硬约束：

- **每个任务、每个泛化轴等权**：任务占 1/32，轴占该任务的 1/5（全局 1/160），单次试次占全局 1/320。没有“高权重任务”可押。
- **每个任务只有 2 次/轴**：方差极大。一个轴两次都失败，该轴就是 0；三次成功可能只是运气。必须用配对/bootstrap，而不是看单次涨跌。
- **180 秒足够做一次“最后 3 厘米”的闭环**：演示中位数约 6–10 秒，DPP/OSC/SVL 花 1–3 秒完全在预算内；但长程任务（T16/T17/T31）要限制重试次数。

## 2. 评分算术与资源分配

### 2.1 排名目标

设任务 \(t\) 第 \(r\) 次运行成功指示为 \(s_{t,r}\in\{0,1\}\)，步骤分为 \(q_{t,r}\in[0,1]\)：

\[
S=\frac{1}{32}\sum_{t=1}^{32}\frac{1}{10}\sum_{r=1}^{10}s_{t,r},
\qquad
Q=\frac{1}{32}\sum_{t=1}^{32}\frac{1}{10}\sum_{r=1}^{10}q_{t,r}.
\]

排名先比 \(S\)，再比 \(Q\)，再比提交时间。写成轴级：

\[
S=\frac{1}{160}\sum_{t=1}^{32}\sum_{a=1}^{5}S_{t,a},
\qquad
S_{t,a}=\frac{1}{2}\sum_{r=1}^{2}1[\text{success}_{t,a,r}].
\]

### 2.2 杠杆与方差

- 单个任务从 0 → 30%：`+0.30/32 = +0.94pp` 全局。
- 单个轴在 32 个任务上平均 +10pp：`+0.10/5 = +2.0pp`。
- 终局放置在所有任务上 +10pp，若到达终局的概率 `q≈0.6`：`+0.10×0.6 = +6.0pp`。
- 最差 6 个任务从 0 → 30%：`6×0.94 = +5.6pp`。
- 步骤分 +10：**只有在成功率完全同分时才可能改变排名**，期望权重接近 0。

**方差**：p=0.3、n=320 时全局 SE = \(\sqrt{0.3\times0.7/320}=2.56\)pp；单任务 n=10 时 SE≈14.5pp。**单任务涨跌 1–2 次完全可能是噪声**。因此：

- 主决策用 32 任务分层配对 bootstrap，不用单任务均值。
- 先追求“跨任务普遍 +5pp”，再追求“单任务 +20pp”。
- 任何小于 +3pp 的全局提升，在 320 次试次下都不应宣称有效。

### 2.3 步骤分作为 X 光片

```text
gap_t = step_score_t − success_rate_t
```

- `gap_t > 15pp`：能完成大部分步骤，倒在终局 → 投 DPP/OSC/SVL+。
- `gap_t < 5pp`：早期就失败 → 投感知/抓取/SSG+/ICR+。
- 两者都低：任务本身难或数据少 → 投数据/调试槽，不要盲目加终局模块。

占位榜 8 个模型的 `步骤分−成功率` 平均约 **+8.6pp**，只能当“失败集中在后段步骤”的弱先验；真实榜单/调试槽出来后，这张表才是资源分配依据。

### 2.4 预算分配建议

```text
终局放置（DPP/OSC/SVL+）           60%
最差任务组合（portfolio/调试槽）    25%
轴级鲁棒（OCA/NRB/ICR+）            15%
```

这里的“预算”指研究/工程注意力，不是算力。理由：终局是 32/32 任务的通关闸门，且跨 5 轴同时起作用；最差任务组合的边际收益接近终局，但风险更低；轴级鲁棒是乘数，不应单独吃掉主预算。

### 2.5 为什么是“终局 + 最差任务”而不是“只补最弱轴”

第 7 轮的“补最弱轴”逻辑在成功率优先规则下不够：一个轴最多贡献 20pp 全局（1/5），而终局放置对所有轴都起作用；同时，最差 6 个任务从 0→30% 也能贡献 5.6pp，且不依赖“终局一定可达”的假设。两者组合比单押终局更稳。

## 3. DOPL-GPR 架构

### 3.1 总览

```text
language（160 条复述之一）+ 4 路相机 + proprio
        │
        ▼
SSG+：官方评分步骤图 → 当前步骤 s、谓词、撤销转移、gap 诊断
        │
        ├─ OCA：最近 N 帧/proprio/动作 → context token z_t → AdaLN
        │
        ├─ 感知：物体/容器 mask、6D 位姿、点云；容器可能在手
        │
        ├─ 若 s 是终局放置/插入/堆叠/闭合/倾倒：
        │     ICR+ 检索 K 条演示 → μ, Σ（容器系释放位姿）
        │     DPP：采样 δ ~ p_θ(δ | l, skill, P_O, P_R, X_0, μ, Σ, z_t)
        │           X_i = μ ⊕ δ_i，投影成 2D 锚点
        │     OSC：对 X_i 打分（成功概率 + 短程后果 + 不确定性）→ X*
        │     SVL+：伺服 → 缓放 → 稳定/谓词校验 → nudge/regrasp/retry
        │
        └─ 否则：
              GPR-VLA / WLA action expert → action chunk
        │
        ▼
OML：记录 (task, step, X*, embedding, outcome, step_score)
        │
        ▼
NRB：官方 human 备注剧本（先叠后撤/拉链拉开/拧回瓶盖…）→ 恢复训练
```

一句话：**把公开评分步骤当骨架，把 33k 演示当终局位姿库，把扩散当多峰提议器，把评论家当成功率守门员，把 10 次试次当在线校准流。**

### 3.2 SSG+：评分步骤图门控

- **输入**：`info.json` 的 `score_steps`（已抓全 32 个任务）、5 条英文复述/中文描述、官方 `generalization` 备注。
- **构建**：每任务一个线性图 `s0 → s1 → … → sk`，附权重 \(w_i\)；指令匹配 = 精确串匹配（160 条）+ 规范化（小写/去标点）+ 嵌入兜底。
- **运行**：`s_t` 仅在“谓词头 + 事件校验”确认完成后前进；未确认则重试/回退；`human` 撤销事件触发 `s_t ← s_{t-1}`。
- **谓词头**：轻量分类器（视觉特征 + 物体相对位姿 + 接触/静止统计），用演示自动标注 + 少量人工抽检。
- **收益**：(a) 防跳步/防假完成（直接提成功率）；(b) 把每步完成概率显式化 → 重试预算按 \(w_i\) 分配；(c) 给 DPP/ICR+ 提供相位标签；(d) 输出 `gap_t` 诊断。
- **风险**：谓词噪声会误判完成/撤销；用演示统计校准阈值，并保留“人工备注触发”的硬规则。

### 3.3 ICR+：物体中心检索与先验

- **库**：官方 33k → 按“任务 × 步骤相位”切段（抓取段、终局放置段、闭合/插入段），每段 1–2 秒。
- **键（只取关系与运动，不取全局外观）**：
  - 指令复述嵌入；
  - 技能标签（grasp/transport/place/insert/stack/close/pour/fold）；
  - 物体关键点相对容器关键点的位移/朝向；
  - 容器相对底座/腕部的位姿；
  - 最近 1 秒光流统计/EE 速度。
- **值**：容器系释放位姿 \(H_i\)、缓存上下文编码、动作先验（K 段动作的稳健均值）。
- **持容器帧**：若容器被另一只手拿着，目标坐标系不是桌面，而是**持容器腕部坐标系**；否则用检测到的容器/目标区域坐标系。T05/T10/T26/T28/T30 必须支持这一分支。
- **注入**：DPP 的条件 \(μ, Σ\)；GPR-VLA 的上下文 token；动作先验以小权重融合，防覆盖。
- **延迟**：HNSW 检索 <5ms；编码全离线；目标 `get_action` p99 <100ms。

**证据链**：SPOT 用物体中心 SE(3) 位姿轨迹扩散，解耦 embodiment 与感知[S13]；FlowRetrieval 的运动相似度优于视觉/语言相似度[S21]；ICI-VLA 的相位对齐 + 防复制[S17]；RA-VLA 的缓存编码控延迟[S18]；Retrieval-VLA 的物件中心关键点抗 clutter[S20]。

### 3.4 DPP：物体中心 SE(3) 残差扩散

#### 3.4.1 表示

对任务 \(t\)、步骤 \(s\)、演示 \(i\)，在释放时刻取：

\[
H_i = (T_B^{R})^{-1}\, T_B^{G_i}(t_i^{rel}) \in SE(3),
\]

其中 \(T_B^{G_i}\) 是夹爪在 base 系的位姿，\(T_B^{R}\) 是目标容器/表面（或持容器腕部）坐标系。\(H_i\) 表示“物体/夹爪在目标坐标系下的释放关系”，跨外观、背景、绝对位置共享。

对检索到的 K 条演示，计算稳健均值 \(μ\) 与切空间协方差 \(Σ\)：

\[
μ = \operatorname{FréchetMean}_{SE(3)}(H_1,\dots,H_K),
\qquad
δ_i = \operatorname{Log}(μ^{-1}H_i),
\qquad
Σ = \operatorname{Cov}(\{δ_i\}).
\]

#### 3.4.2 扩散目标

在切空间定义残差 \(δ \in \mathbb{R}^6\)（平移 3 + 旋转 so(3) 3），解码 \(X = μ \operatorname{Exp}(δ)\)。前向：

\[
q(δ_t \mid δ_0)=\mathcal{N}(\sqrt{\barα_t}\,δ_0,(1-\barα_t)I).
\]

反向网络 \(ε_θ(δ_t,t,c)\) 的条件：

\[
c=[E_l(l),E_{skill}(s),P_O,P_R,X_0,μ,Σ,z_t],
\]

其中 \(P_O\) 是物体点云（物体系），\(P_R\) 是目标区域点云（容器系），\(X_0\) 是当前夹爪位姿，\(z_t\) 是 OCA 的上下文 token。损失：

\[
\mathcal{L}_{DPP}=\mathbb{E}_{t,δ_0,ε}\left[\|ε-ε_θ(δ_t,t,c)\|_2^2\right]
+\lambda_{geo}\mathcal{L}_{geo}
+\lambda_{div}\mathcal{L}_{div}.
\]

- \(\mathcal{L}_{geo}\)：解码后的 \(X\) 与演示/几何约束（不穿透、在容器内、朝向可达）的惩罚。
- \(\mathcal{L}_{div}\)：可选多样性正则，防止 K 个样本塌缩到同一模态。
- 训练时对条件做 dropout（语言/技能/点云），支持 classifier-free guidance。

#### 3.4.3 采样与选择

- 从检索先验初始化：\(δ_T \sim \mathcal{N}(0,\Sigma)\)（小方差）或 ADPro 式“几何引导的初始噪声”；同时保留一部分从宽先验 \(N(0,I)\) 采样，防止先验过窄导致模态丢失。
- 4–8 步 DDIM/Flow 采样，K=8 个候选；按 SE(3) 距离去重（保留 4–6 个不同模态）。
- 对每个候选解码 \(X_i\)，投影成头/腕相机的 2D 锚点（十字 + 朝向 + 容差圈），作为 GPR-VLA/SVL+ 的条件。
- **选择交给 OSC**，不直接执行均值。中位数回归会把“放左边/放右边”平均成“放中间”的不存在位姿；扩散 + 评论家正是为了避免这一点。

#### 3.4.4 为什么不是“动作轨迹扩散”

动作头 diffusion 解决的是“单步/短程动作的多模态”；32 个任务的失败大量发生在**终局关系位姿**：叠碗是叠在碗 1 还是碗 2？插头是插第一个孔还是第二个？相框是立在支架上还是平放？这些是**任务空间的离散/多峰选择**，不是关节空间的抖动。DPP 只负责“终局目标”，动作由底座/ SVL+ 负责；两者解耦，便于单模型审计与延迟控制。

**证据链**：Diffusion Policy 在多模态动作上平均提升 46.9%[S12]；SPOT 的物体中心 SE(3) 扩散[S13]；ADPro 的流形约束 + 任务感知初始化在测试时提升 9pp[S24]；AnySlot 的生成式视觉目标在零样本槽位放置达 82%[S14]；SpaceVLA 的抓/放锚点把放置误差降到 0.7cm[S15]；Spa-Bench 指出 OOD 空间 grounding 是真机主要瓶颈（ID 67.5–73.3% → OOD 40.7–52.0%）[S16]。

### 3.5 OSC：在线成功评论家

#### 3.5.1 结构

- **输入**：候选 \(X\)、物体/容器点云、当前观测、技能、DPP 条件、SVL+ 预测的接近轨迹特征。
- **输出**：成功概率 \(p_\phi\)、短程后果 \(g_\psi\)（掉落/滑移/遮挡/碰撞风险）、不确定性 \(u\)（3 个头的方差）。
- **训练**：正样本 = 演示释放位姿；负样本 = 反事实扰动（平移 ±2cm、旋转 ±10°、错槽位、过高释放、碰撞姿态）+ 真实失败；损失 = BCE + 排序损失 + 校准正则：

\[
\mathcal{L}_{OSC}=\mathrm{BCE}(p_\phi,y)
+\lambda_{rank}\max(0,m-(p_\phi^{+}-p_\phi^{-}))
+\lambda_{cal}\mathrm{ECE}.
\]

- **单模型边界**：3 个评论家头共享同一 trunk，属于同一 checkpoint 的多头，不是 3 个独立模型；模型卡逐项披露。

#### 3.5.2 在线校准

- 每任务维护 OML 记忆；每次试次后，用记忆中的 `(X, outcome)` 更新**校准参数**（Platt scaling / beta calibration）或评论家最后一层（仅 safe/aggressive 模式）。
- 默认 safe 模式：**只更新校准参数**，不更新基座/评论家 trunk；frozen 模式：只记录不更新；aggressive 模式：最后一层 + TTT fast weights，仅在官方书面确认后启用。
- 校准目标：ECE < 0.05；若 ECE 超标，降低评论家权重，退回 VLA。

#### 3.5.3 风险感知选择

\[
X^*=\arg\max_{X_i}\left[\hat p_i-\lambda_u u_i-\lambda_{risk} g_\psi(X_i)\right].
\]

- 若 \(\max_i \hat p_i < \tau\)（默认 0.5），不选 DPP 候选，退回 GPR-VLA 的保守动作/锚点伺服。
- 若候选间 \(u\) 很大，优先选“低风险 + 中等成功率”，而不是“高成功率 + 高不确定性”。
- 在线校准后的 \(\hat p\) 只用于选择，不进入排名计算。

**证据链**：TEMPO 用冻结 critic + 熵正则 + 记忆做无奖励 TTA，最高 80% 提升[S23]；DexPIE 用真实世界经验 + critic + DAgger 提升 37.3%[S25]；RouteRLT 证明“何时在通用 VLA 与精度专家之间切换”本身是问题[S26]。我们不跑在线 RL/PPO，只做“评论家选择 + 校准”。

### 3.6 OCA：在线上下文适配

- **编码**：最近 N=8 帧的视觉嵌入、proprio、历史动作 → GRU/Transformer → context token \(z_t\)。
- **注入**：AdaLN 调制 GPR-VLA action expert 与 DPP 的条件：

\[
h'=h\odot(1+\gamma(z_t))+\beta(z_t).
\]

- **训练**：对相机位姿、光照、背景、执行器偏置、物体位置做 shift 增强；context dropout；辅助任务 = 下一动作/下一帧预测。
- **测试时**：只更新每 episode 的 context buffer，不更新权重；`reset()` 清空。
- **与 OML 的分工**：OCA 处理“当前 episode 的观测统计偏移”；OML 处理“本任务已试过的结果”；两者都不跨任务。

**证据链**：Self-Adaptive VLA 用 context token + AdaLN，在硬件偏移下恢复 >80% 性能[S22]；RoboTTT 用 test-time training 的 fast weights 做到 8K 时间步上下文[S20]；TTT-RM 把 TTT 当残差记忆[S21]。OCA 是其中**最合规、最轻量**的一层。

### 3.7 OML：每任务试次记忆

- **存储**：`(task, step, X*, object_embedding, container_embedding, outcome, step_score, timestamp)`；cap 64；FIFO + 失败样本优先保留。
- **用途**：
  1. 检索重加权：与当前场景相似且成功的试次 → 提高对应演示权重；失败试次 → 负库。
  2. 评论家校准：把记忆当校准集，更新 Platt/beta 参数。
  3. 失败规避：若当前候选与失败记忆的 SE(3)/嵌入距离过近，降权。
- **清理**：任务结束清空；不跨任务；全局只保留技能级先验（不含任务身份）。
- **合规**：OML 是数据，不是模型；模型卡说明“评测流内维护每任务 64 条结果记忆”。

### 3.8 SVL+：落点闭环

```python
def place_and_verify(step, obs, plan, budget=2):
    for attempt in range(budget + 1):
        anchor = project_to_anchor(plan.X, obs)          # 3D -> 2D
        ctx    = ICR.retrieve(step, obs, k=8)
        for chunk in stream(policy.act(obs, anchor, ctx, s=step)):
            send(chunk)                                  # 30Hz
            if predicate_met(step, obs):
                break
        if not predicate_met(step, obs):
            plan = revise(plan, obs, reason=diagnose(step, obs)); continue
        open_gripper(slow=True); sleep(0.5)              # 缓放 + 静置
        if stable(step, obs, window=0.5) and predicate_met(step, obs):
            return True
        if repairable(step, obs):
            plan = nudge_plan(step, obs)                 # 推正/轻压
        else:
            regrasp(step)                                # 重抓
    return False
```

- `stable`：物体相对位姿在 0.5s 内位移 < ε_rel（ε 由演示统计给出）+ 谓词保持；学习型稳定分类器 + 几何检查双保险。
- `predicate_met`：SSG+ 谓词头 + 事件（接触/静止）。
- 预算：普通任务 ≤2 次；长程任务（T16/T17/T31）≤1 次；总时长守卫兜底。
- 与 OSC 的分工：OSC 选“放哪里”，SVL+ 管“怎么放稳、放完怎么验”。

### 3.9 NRB：官方备注恢复

用公开 `generalization` 备注构造破坏→恢复对，训练恢复策略；不把备注当评测泄漏，只当课程。

| 任务 | 官方备注（节选） | 场景化 | 恢复目标 |
|---|---|---|---|
| T27 | 叠了第二个之后拿下第二个 | 移除 bowl2 | 重新放置 bowl2 → 继续 bowl3 |
| T19 | 拉上拉链之后拉开 | 拉开拉链 | 重新拉合 |
| T14 | 拧开盖子之后拧动回来 | 盖回瓶盖 | 再拧开 → 倒药 |
| T17 | 笔盒合上之后手动打开 | 打开笔盒 | 重新合上 |
| T10 | 将插头拔起 | 拔起插头 | 重新插入 |

### 3.10 底座与单模型集成

- 底座：**WLA-1.0-Base**（6B，UnifoLM-ER-1 4B + MMDiT action expert，约 2,500 小时、64 任务，Apache-2.0）[S27]；若算力/许可不合适，换同量级开源 VLA，架构不变。
- GPR-VLA：语言/多视图/本体 → 动作 chunk；LoRA/action expert 微调。
- DPP/OSC/OCA 是同一 checkpoint 的辅助头/适配模块；OML 是数据；SSG+/SVL+ 是确定性控制代码。**不混合多个独立模型**。
- 训练时联合优化：

\[
\mathcal{L}=\mathcal{L}_{policy}+\lambda_1\mathcal{L}_{DPP}
+\lambda_2\mathcal{L}_{OSC}+\lambda_3\mathcal{L}_{OCA}.
\]

推理时可以只调用必要模块（简单任务不走 DPP），但仍是同一模型。

## 4. 训练配方与数据引擎

### 4.1 放置位姿库

- 对 33k episode 自动检测释放时刻：夹爪开度突增 + 物体相对运动 + 谓词完成；人工抽检 5%。
- 计算每条演示的 \(H_i\)（容器系/腕部系）。
- 按任务×步骤聚类，估计 \(μ, Σ\)、任务容差 \(τ_t\)（95 分位放置误差）。
- 透明/布料/小件：6D 位姿不可靠时，回退到关键点/光流统计或 ICR+ 动作先验；DPP 不硬上。

### 4.2 反事实负样本

- 对每个正样本扰动：平移 ±1/2/5cm、旋转 ±5/10/20°、错槽位、过高释放、碰撞姿态、错误物体。
- 用几何谓词/仿真/真机少量试次打标签；难负样本优先（接近决策边界）。
- 目标：OSC 的 AUROC > 0.85，ECE < 0.05；否则不启用评论家选择。

### 4.3 OCA 训练

- shift 增强：相机外参扰动、光照/色温、背景替换、执行器偏置、关节零位偏移。
- context dropout：训练时随机遮住部分历史，防止依赖单一帧。
- 辅助损失：下一动作预测/下一帧嵌入预测；不引入额外模型进推理。

### 4.4 恢复数据

- 官方备注剧本 + 合成扰动 + 少量真机恢复演示。
- 重点：T27/T19/T14/T17/T10；覆盖“人为干扰”轴。
- 恢复段单独加权，避免被正常演示淹没。

### 4.5 算力估算

| 阶段 | 资源 | 时间 |
|---|---|---|
| 底座微调（LoRA/action expert） | 8×H100 | 5–7 天 |
| DPP/OSC/OCA 训练 | 8×H100 | 2–3 天 |
| 检索库/位姿库构建 | 8×H100 + CPU | 1–2 天 |
| 校准/消融 | 1–2×H100 | 2–3 天 |
| 真机调试 | 官方远程/合作 G1 | 按槽位 |

> 若只有 24GB 显存：底座用 LoRA/量化，DPP/OSC 用小头；但 6B 全量微调不现实，需提前确认。

## 5. 实验设计

### 5.1 离线

| 指标 | 定义 | 目标 |
|---|---|---|
| 放置位姿误差 | 解码 \(X\) 与 held-out 演示的平移/旋转误差 | 中位 <1cm / <5° |
| 检索召回 | 正确任务/步骤的演示进入 top-K | >90% |
| 评论家 AUROC | 成功 vs 扰动/失败 | >0.85 |
| 校准 ECE | 预测成功率 vs 实际 | <0.05 |
| 恢复成功率 | 备注扰动后的恢复 | >60% |

### 5.2 真机调试

- 不计分单任务调试槽：优先 T27（堆叠）、T10（插排）、T19（拉链）、T26（网线）、T05（拔网线）。
- 每个版本 1–2 槽；每槽至少 10 次；记录成功/步骤/失败模式/延迟。
- 判定：DPP+OSC 终局成功率 ≥ +10pp，且无简单任务回归，才允许进计分跑。

### 5.3 消融

| ID | 配置 | 验证 |
|---|---|---|
| E0 | WLA/GPR-VLA 基线 | 复现 |
| E1 | +SSG+ | 步骤门控/防跳步 |
| E2 | +ICR+ 先验 | 检索增益 |
| E3 | +DPP（K=1，均值） | 扩散 vs 中位数 |
| E4 | +DPP（K=8） | 多峰采样增益 |

补充消融：K∈{1,2,4,8,16}；扩散步数∈{2,4,8}；物体中心 vs 世界坐标；持容器帧 on/off；评论家集成头数；校准 on/off；记忆 cap∈{16,64,256}；DPP 只在终局 vs 全程。

### 5.4 统计

- 320 次计分试次，按任务分层配对 bootstrap；报告 95% CI。
- 单任务 n=10，不报告“单任务显著”；用层级贝叶斯（任务随机效应）估计全局效应。
- 多重比较：消融用 Holm-Bonferroni；探索性分析标注。
- 决策阈值：全局 +3pp 才宣称有效；+5pp 才建议提交；单任务 +10pp 只作为调试信号。

### 5.5 Go/No-Go

- **G1**：离线放置误差/评论家 AUROC 达标 → 进真机。
- **G2**：T27/T10 调试槽终局 +10pp → 进全量训练。
- **G3**：32 任务离线/远程回放无简单任务回归 → 计分跑。
- **G4**：p99 <100ms、soak 4h 无超时 → 提交。
- 任一失败：回退 PILOT-GPR（OPT+SVL）或纯底座；不硬上 DPP。

## 6. 创新点清单（持续迭代；动机/差异/可行性/资源/步骤/风险/状态）

> 状态：**押注**=本轮主线；**升级**=旧点改造；**保留**=沿用；**研究**=有前景但合规/证据不足；**砍**=不做。

### I1 DPP 物体中心 SE(3) 残差扩散（押注）
- **动机**：终局放置是 32/32 任务的闸门；演示放置是多峰的，中位数回归会平均出不存在的位姿。
- **差异**：不是“动作头换 diffusion”，而是以检索先验 \(μ,Σ\) 为条件、在物体中心切空间扩散“释放关系位姿”；输出 K 个候选，不直接执行均值。对比 SPOT（轨迹扩散）、ADPro（动作扩散）、Diffusion Policy（动作 chunk），建模对象不同。
- **可行性**：33k 演示已有 EE 位姿与释放时刻；SE(3) 扩散是成熟工具；物体/容器 6D 位姿可用 FoundationPose/关键点 PnP。
- **资源**：8×H100 2–3 天；位姿库 1–2 天；单卡推理 10–20ms。
- **步骤**：释放检测 → \(H_i\) 库 → 检索 \(μ,Σ\) → 训练 DPP → 采样/投影 → 调试槽验证。
- **风险**：透明/布料/小件 6D 位姿失效 → 分桶回退 ICR+/VLA；先验过窄 → 宽先验混合；扩散延迟 → 蒸馏/少步。
- **状态**：主线。

### I2 OSC 学习型成功评论家 + 短程后果（押注）
- **动机**：成功率优先；生成 K 个候选后，需要一个“成功率守门员”，而不是随机选/选最像演示的。
- **差异**：不是 RL critic（无奖励、无在线 PPO），而是“候选选择器 + 校准器”；用反事实负样本和真实试次训练；输出可校准概率。
- **可行性**：小 MLP/Transformer 头；演示 + 扰动即可训练；推理 2–3ms。
- **资源**：1–2 天训练；无需额外真机数据即可起步。
- **步骤**：正/负样本 → 训练 → 离线 AUROC/ECE → 接入 DPP → 调试槽校准。
- **风险**：过自信 → 集成 + 温度校准 + 阈值回退；分布外候选 → 不确定性惩罚；单模型审计 → 多头披露。
- **状态**：主线。

### I3 OCA 在线上下文适配（押注）
- **动机**：背景/位置/硬件偏移是 5 轴泛化的共同乘数；重训来不及，在线更新权重又不合规。
- **差异**：context token + AdaLN，只更新每 episode 的上下文，不更新基座；与 Self-Adaptive VLA 同源，但加入 DPP 条件与 shift 增强。
- **可行性**：轻量编码器；推理 <5ms；不需要新数据。
- **资源**：1–2 天训练；1 人周工程。
- **步骤**：编码器 → shift 增强 → context dropout → 接入 → 背景/干扰轴验证。
- **风险**：上下文过拟合当前 episode → dropout/长度限制；延迟 → 降 N/缓存。
- **状态**：主线（safe 模式）。

### I4 OML 每任务试次记忆 + 校准（押注，合规敏感）
- **动机**：每任务 10 次试次是官方给的“在线学习信号”；不利用可惜，利用要合规。
- **差异**：不是跨任务训练，而是任务内非参数记忆 + 校准；任务结束清空；默认只校准最后一层/温度，不动基座。
- **可行性**：cap 64 条，CPU 内存；检索/校准 <1ms；实现简单。
- **资源**：1 人周；无额外算力。
- **步骤**：记忆 schema → 检索重加权 → Platt/beta 校准 → 消融 → 合规审计。
- **风险**：规则不允许评测内更新 → frozen 模式；记忆污染 → 清空/负库；过拟合小样本 → 强先验/温度上限。
- **状态**：主线（safe），aggressive 待书面确认。

### I5 SSG+ 评分步骤图 + gap 诊断（升级）
- **动机**：官方已公开步骤+权重；成功=全步骤；防跳步/假完成，且给出“钱丢在哪步”。
- **差异**：在 SSG 基础上增加谓词/事件双门控、撤销回退、`gap_t` 诊断；不改变官方指令，只在内部翻译成步骤图。
- **可行性**：确定性代码 + 小谓词头；32×5 复述可精确匹配。
- **资源**：无额外数据；CPU；1 人周。
- **步骤**：解析 info.json → 图 → 谓词头 → reset 状态机 → gap 报表。
- **风险**：谓词噪声 → 演示统计校准；语言未覆盖 → 嵌入兜底。
- **状态**：升级保留。

### I6 ICR+ 物体中心检索 + 持容器腕部系（升级）
- **动机**：33k 是现成少样本库；终局放置需要“相似关系”的演示，而不是相似外观。
- **差异**：键只取关系/运动/技能；增加“容器在手”的腕部坐标系；跨任务技能级检索，缓解稀有任务数据少。
- **可行性**：缓存编码（RA-VLA 式）+ HNSW；26 万段 <1GB；检索 <5ms。
- **资源**：8×H100 1–2 天建库；CPU 服务。
- **步骤**：切段 → 建键 → 缓存 → 检索 \(μ,Σ\) → 延迟压测。
- **风险**：透明任务键失效 → 回退动作先验；背景泄漏 → 键剔除全局外观。
- **状态**：升级保留。

### I7 SVL+ 学习型落点闭环（升级）
- **动机**：释放失败（掉落/弹跳/未到位）靠“放完就完”无法发现；终局是闸门。
- **差异**：手写谓词 → 学习型稳定分类器 + OSC 门控；增加 nudge/regrasp/retry 预算与长程任务上限。
- **可行性**：控制循环 + 小分类器；180 秒预算足够 1–2 次重试。
- **资源**：1 人周；演示 + 扰动数据。
- **步骤**：稳定分类器 → 校验逻辑 → nudge/regrasp → 预算守卫 → 调试槽。
- **风险**：重试拖长时长 → 预算/总时长守卫；误判稳定 → 双保险。
- **状态**：升级保留。

### I8 NRB 官方备注恢复课程（保留）
- **动机**：人为干扰轴是 5 轴之一；官方备注直接给出干扰剧本。
- **差异**：把备注变成“破坏→恢复”训练对，而不是评测时硬编码。
- **可行性**：备注公开；合成扰动 + 少量真机恢复演示。
- **资源**：1–2 人周；数据增强。
- **步骤**：解析备注 → 场景化 → 恢复演示 → 训练 → 干扰轴验证。
- **风险**：备注编号含义未核实 → 只当课程，不当评测分布；合成到真实 gap → 真机校准。
- **状态**：保留。

### I9 GPR-VLA / WLA-1.0 底座（保留）
- **动机**：需要一个强通才底座；WLA-1.0 6B、Apache-2.0、MMDiT action expert，是现成起点。
- **差异**：不追求再训一个 14B WAM；把研究火力放在终局头/在线层，底座保持单模型。
- **可行性**：HF/GitHub 公开；24GB 可微调（LoRA/量化）；远程 API 部署。
- **资源**：8×H100 5–7 天；推理 30–50ms。
- **步骤**：复现 → 33k 微调 → 接入 DPP/OSC/OCA → 蒸馏/量化。
- **风险**：许可证/商用边界 → 核对 Apache-2.0；6B 延迟 → 量化/端口并发；底座本身弱 → 换同量级 VLA。
- **状态**：保留。

### I10 技能条件共享放置头 + 双手关系（新增，并入 DPP）
- **动机**：32 任务可分解为 8 类技能；同一套“抓-搬到-放到关系”应跨物体共享；双手任务的目标坐标系可能在手上。
- **差异**：技能 embedding 条件化一个共享 DPP/动作头，而不是 32 个任务头；显式持容器腕部系。
- **可行性**：技能标签可从任务/步骤自动生成；腕部系从 proprio 直接可得。
- **资源**：并入 DPP 训练；无额外大模型。
- **步骤**：技能标签 → 条件注入 → 腕部系分支 → 跨任务消融。
- **风险**：技能分错 → 多标签/软条件；腕部系噪声 → 滤波/回退桌面系。
- **状态**：并入 I1/I6，不单列主线。

### I11 不确定性感知的试次分配 / 任务组合（新增）
- **动机**：每任务只有 10 次，方差大；调试槽贵；应把有限试次投到“最可能提升全局成功率”的任务/轴。
- **差异**：不是平均用力，而是用评论家不确定性 + gap + 任务权重做 portfolio；调试槽只验最关键的 3 个任务。
- **可行性**：离线统计 + 简单 bandit；不需要额外模型。
- **资源**：1 人周；CPU。
- **步骤**：定义效用 → 估计不确定性 → 分配调试/重试 → 复盘。
- **风险**：过拟合小样本 → 强先验/分层；占用比赛时间 → 自动化。
- **状态**：工程策略，中优先。

### I12 TTT fast weights（研究，默认不进计分）
- **动机**：如果官方允许评测流内更新，fast weights 可能带来最强在线适应。
- **差异**：RoboTTT/TTT-RM 的 fast weights/残差记忆，作用在动作专家的小矩阵，不动基座。
- **可行性**：研究代码可复现；但合规风险高、延迟/稳定性未知。
- **资源**：2–3 人周；单卡实验。
- **步骤**：离线复现 → 冻结/安全模式对比 → 书面确认 → 才考虑计分。
- **风险**：规则不允许 → 只做研究；在线不稳定 → 回退 OCA/OML；延迟 → 只在小矩阵。
- **状态**：研究轨道，默认不进主路径。

### 已砍清单（跨轮）

- 把步骤分当第二目标（规则已明确只做同分裁决）。
- 全 32 任务高保真孪生（成本高、收益不确定）。
- 自由仿真数据/仿真 RL（sim-to-real gap 未验证）。
- 运行时仿真/MPC（延迟与接口不允许）。
- 每任务 LoRA/模型合并（违反单模型精神，审计复杂）。
- 多模型 ensemble/按任务切模型（规则明确禁止）。
- 硬编码任务坐标/槽位（泛化轴直接击穿）。
- 无力控 API 却宣称力控（接口只有位置目标）。
- 评测期在线 PPO/DAgger（无奖励、样本少、合规风险）。
- 14B WAM 进运行时（延迟/算力不现实）。
- FLEET“第六轴”（降为工程检查单）。
- 大规模自采数据先于规则确认（外部数据边界未核实）。

## 7. 风险、合规与开关

### 7.1 规则合规矩阵

| 事项 | 规则现状 | 我们的默认 | 需要确认 |
|---|---|---|---|
| 单模型 | 明确：一个模型完成 32 任务，不得混合多个模型 | DPP/OSC/OCA 同一 checkpoint；OML 数据；不 ensemble 独立模型 | 多头/辅助头是否算同一模型；模型卡怎么写 |
| 在线学习 | 未写允许/禁止 | frozen/safe：只更新上下文/记忆/校准；不动基座 | 评测流内更新校准参数是否允许 |
| 外部数据 | 未核实 | 只用官方 33k + 公开预训练权重 | 自采/实验室数据、论文权重边界 |
| 部署 | 自部署，远程 API | 单服务多端口；p99 <100ms；soak | N 台机器人/端口/并发上限 |
| 调试 | 单任务不计分 | 只用于发布门，不刷榜 | 可用次数/成本/是否随机化 |
| 动作 | 位置目标（joint/ee） | 行为柔顺，不宣称力控 | 是否可能开放力/刚度 |

### 7.2 在线学习三档开关

```yaml
online_mode: safe          # frozen | safe | aggressive
frozen:
  update: none
  use_memory: false
safe:
  update: calibration_only # Platt/beta, last-layer optional
  use_memory: true
  memory_cap: 64
  clear_per_task: true
aggressive:
  update: last_layer + ttt_fast_weights
  require_written_approval: true
  fallback: safe
```

- 默认 `safe`；提交前用 `frozen` 跑一次审计，证明“即使不更新也能工作”。
- `aggressive` 只在官方书面确认后启用；模型卡写明更新范围/频率/数据。

### 7.3 单模型审计

- 一个 checkpoint 包含：GPR-VLA 主干、DPP 头、OSC 头、OCA 编码器。
- OML 是运行时数据；SSG+/SVL+ 是确定性代码；ICR+ 是检索库。
- 模型卡逐项列出：参数量、训练数据、辅助头、检索库来源、在线更新范围、延迟。
- 不调用外部 API/第二个模型；不在评测时下载权重。

### 7.4 主要风险

| 风险 | 触发 | 缓解 |
|---|---|---|
| 评论家过自信 | OOD 候选/小样本 | 集成 + 温度校准 + `p<0.5` 回退 |
| 扩散先验过窄 | 检索到错误演示 | 宽先验混合 + 多样性采样 + OSC |
| 透明/布料 6D 失效 | T16/T19/T23/T31 | 分桶回退 ICR+/VLA；不硬上 DPP |
| 延迟超标 | K=8/6B | 降 K/步数、蒸馏、只在终局调用 |
| 记忆污染 | 失败试次 | cap、清空、负库、强先验 |
| 统计噪声 | 单任务 10 次 | 分层 bootstrap、+3pp 阈值 |
| 规则不允许在线 | 官方解释 | frozen 模式、邮件确认、模型卡 |
| 占位榜误导 | 29.7% | 不据此调参；真实榜单后重跑 gap |
| 长程任务超时 | T16/T17/T31 | 重试上限、总时长守卫 |
| 外部数据/许可 | WLA/检测器 | 逐个核对许可证；准备替代 |

### 7.5 失败模式与回退

```text
DPP 失败 → ICR+ 动作先验 / GPR-VLA 直接动作
OSC 失败 → 选最接近演示的候选 / 锚点伺服
OCA 失败 → 冻结上下文 / 只用当前帧
OML 失败 → 清空记忆 / 只用离线先验
SVL+ 失败 → 一次保守放置 / 放弃重试
整体失败 → PILOT-GPR（OPT+SVL）或纯底座
```

## 9. 与公开工作的差异（避免“重复造轮子”）

| 公开工作 | 它做了什么 | 我们不同在哪 |
|---|---|---|
| Diffusion Policy[S12] | 动作 chunk 扩散，多模态动作 | 我们扩散“终局关系位姿”，动作仍由底座出 |
| SPOT[S13] | 物体中心 SE(3) 位姿轨迹扩散 | 我们只扩散终局残差，条件化检索先验，并用评论家选 |
| ADPro[S24] | 测试时流形约束 + 任务感知初始化 | 我们用检索先验初始化 + 成功率评论家，不做无监督测试时优化 |
| AnySlot[S14] | 生成式视觉目标做槽位放置 | 我们输出 SE(3) 关系位姿 + 评论家，不依赖 2D 生成图 |
| SpaceVLA[S15] | 抓/放锚点 overlay | 我们把锚点作为 DPP 的可视化条件，不替代 3D 位姿 |
| Self-Adaptive VLA[S22] | context token + AdaLN 适应硬件偏移 | 我们把它用于背景/位置/干扰轴，并与 DPP/OML 组合 |
| TEMPO[S23] | 冻结 critic + 熵正则 + 记忆做 TTA | 我们不做策略优化，只做候选选择 + 校准 |
| DexPIE[S25] | 真实经验 + DAgger + critic 改策 | 我们不在评测中 DAgger/更新基座 |
| RouteRLT[S26] | 通用 VLA 与 RL 专家按相位路由 | 我们不训 RL 专家；路由是 DPP/评论家/回退 |
| MolmoAct2[S29] | 动作空间 VLA + 空间推理 | 我们把它当可能的底座/对照，不重复其预训练 |
| Wall-OSS-0.5[S30] | 4B MoT 多模态混合 | 我们关注终局头，不追更大底座 |
| DreamZero[S28] | 14B world-action model | 我们只离线蒸馏/对照，不进运行时 |

## 11. 开放问题

1. 评测流内更新“校准参数/最后一层/记忆”是否允许？单模型定义是否允许同一 checkpoint 的辅助头？
2. 外部数据（自采/实验室）与公开预训练权重（WLA/论文方法）的边界；Apache-2.0 是否可直接商用？
3. 不计分单任务调试的可用次数/成本/是否随机化泛化条件？
4. N 台评测机器人的准确数量；每端口并发/延迟上限；是否支持多端口并行？
5. 语言指令是英文 5 复述之一、中文，还是未见复述？SSG+ 的兜底强度需要知道。
6. 步骤分聚合公式（按 episode 部分分平均？取最好？）；`gap_t` 的真实分布。
7. 官方 `generalization` 备注编号（human_1/human_4/unseen_object_3）是轴编号还是试次编号？评测是否就在这些剧本里采样？
8. 透明/布料/小件任务的 6D 位姿是否可靠？DPP 退化的官方验收标准是什么？
9. 真实榜单何时发布？发布后 29.7% 的工作假设是否仍成立？
10. 若官方开放力/刚度/力矩接口，SVL+/CGP 是否可升级为真正阻抗控制？

**会推翻本轮判断的证据**：

- 真实榜首 >60%，且失败不在终局/接触/干扰；
- 官方明确禁止任何评测流内更新/记忆；
- 单模型规则禁止辅助头/多频率执行；
- T27/T10/T19 调试槽显示 DPP+OSC 终局提升 <5pp；
- 全量演示统计显示放置不是多峰，中位数足够；
- 6B 底座在远程 API 下 p99 无法满足，且蒸馏后性能崩塌。
