## 0. 第 2 轮：先拆掉两个幻觉，再把“抓取”变成一个可验证状态

这一轮先做了三件不浪漫但必要的事：

1. **复核榜单**：`leaderboard.html` 仍然写“即将发布 / Coming Soon”；页面上的 8 行分数是前端脚本随机填的占位；`runs.html` 的 256 条记录点进 `details.html`，视频区原文是“测试视频占位，后续可替换为真实视频文件”。所以 **29.7% 不能当作真实榜首成绩**，只能当“难度先验”。上一轮已经发现 `leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`；本轮复核没有推翻这一点。
2. **复核规则与接口**：单模型完成全部 32 任务、不得混用多个模型；每任务 10 次，5 类泛化各 2 次；单次真机最多 180 秒；总平均成功率优先，步骤分只做 tie-break；选手自部署，平台远程调用；N 个连续端口（示例 N=3）；单任务调试通道不计分。观测里只有 **夹爪位置**，没有电流/力矩/触觉；动作空间是 joint 或 ee，二选一。这意味着“接触力”不能直接测，只能用**位置 + 视觉 + 本体感觉**做代理。
3. **跑了一个真实数据探针**：从 HuggingFace 下载了 5 个任务的 tail parquet（HangCup、StackBowls、PlugCharger、OrganizeTools、PourOutMedicine），提取“夹爪闭合事件”，统计闭合时的孔径、闭合后 40 帧的抬升高度。结果比预想的更有信息量，也更打脸“固定阈值”的做法。

### 0.1 数据探针的四个发现

| 任务（tail 分片） | 臂 | episodes | close 事件 | 闭合孔径中位数 | IQR | 抬升 >3cm | 孔径→抬升 AUC |
|---|---|---|---:|---:|---:|---:|---:|
| HangCup | right | 324 | 463 | 0.14 | 0.10–0.22 | 73.4% | 0.261 |
| StackBowls | left | 143 | 176 | 0.25 | 0.19–0.29 | 84.1% | 0.358 |
| StackBowls | right | 143 | 256 | 0.25 | 0.21–0.27 | 94.9% | 0.585 |
| PlugCharger | right | 169 | 86 | 0.33 | 0.32–0.34 | 19.8% | 0.491 |
| OrganizeTools | left | 76 | 107 | 0.66 | 0.61–0.83 | 95.3% | 1.000 |
| OrganizeTools | right | 76 | 50 | 0.75 | 0.73–0.94 | 100% | n/a |
| PourOutMedicine | right | 173 | 1 | 0.07 | 0.07–0.07 | 0% | n/a |

（tail 分片不是完整数据集；抬升 >3cm 只是“pick 成功”的代理，不是官方 ground truth；AUC 是在同一任务/臂内把所有 close 事件混在一起算的，包含 release/place，所以它不是“抓取分类器”的 AUC。这些限制在产物区写清楚了。）

1. **孔径是对象/部件特异的**：薄杯沿/碗沿约 0.14–0.25，插头约 0.33，工具约 0.66–0.75，倒药任务甚至几乎不闭合（0.07，且 172/173 个 episode 没有 close 事件）。**任何固定阈值都会在另一类任务上错**。
2. **孔径单独不足以判断抓取成功**：HangCup 的 AUC 只有 0.261，StackBowls 左臂 0.358。原因是同一个“闭合”既可能是抓取，也可能是放下/挂上/释放；不结合相位，孔径是歧义的。这直接否定“用孔径阈值做 grasp critic”的偷懒方案，但也说明**相位条件化**是必需的。
3. **多 close 事件不一定是失败**：HangCup 324 个 episode 里 114 个有 2 次 close、11 个有 3 次；StackBowls 右臂 143 个里 106 个有 2 次；OrganizeTools 左臂 76 个里 27 个有 2 次。这些大多是**多物体/多子目标**，不是连续 regrasp。用“close 次数”做失败挖掘会大量误标。
4. **有些任务根本没有 close 相位**：PourOutMedicine 主要是拧盖/倾倒，夹爪保持张开。状态机不能假设“所有任务都以抓取为中心”，必须有 `MANIPULATE/TWIST/POUR` 这类非抓取相位，或者让相位头自己学出来。

### 0.2 新文献把“状态”从暗线推到了明线

本轮读了近两年的几条近邻，结论是：**“状态/承诺验证”正在成为 VLA 的高杠杆方向，但还没有人把它做成 G1 上“位置-only 的抓取验证 + 撤销修复”**。

- **CommitFlow**（arXiv 2609.21908）：把“语义承诺”与“物理条件”分开，冻结基座 VLA，加 commitment monitor + local correction；RoboTwin 10 任务平均 75.9%，比 π0.5 高 22.7%。这是“验证层”有效的最强证据。
- **FLARE**（CVPR 2026 / arXiv 2608.26645）：Retry/Reset 范式，在线 MLLM monitor 仲裁；提升明显，但需要第二个 MLLM、额外 reset 技能库，而且在线延迟高。对“单模型 + 180 秒 + 自部署”不友好。
- **KEMO**（arXiv 2606.23589）：事件驱动关键帧记忆，双机械臂 2–6 子任务，任务成功率 +23.6%、阶段完成率 +34.1%。但它是“记住发生过什么”，不是“验证物理上是否真的成立”。
- **S²-VLA**（IJCAI 2026 / arXiv 2606.27872）：用 belief state 动态门控视觉/语言/动作融合，2B 模型在 LIBERO-Long 96.4%。但 belief 是隐式的，不能直接拿来做“抓空了就重抓”的硬判断。
- **MIM-VLA**（arXiv 2610.08425）：用夹爪电流/位置/速度构造 interaction token，能区分视觉相似物体、做轻柔抓取。但 G1 的 API 只给位置，没有电流；我们不能直接抄。
- **Pseudo-tactile**（arXiv 2503.23835）：明确指出“夹爪闭合”这个观测有歧义：`empty close` 和 `grasp close` 看起来一样；演示数据里“闭合=抓到了”的强相关在测试时会破。这个观察和我们的探针完全一致，是 GVSM 的直接动机。
- **RoboRecover / Recova / Kintsugi**：分别从 benchmark、digital twin、失败 rollout 的角度做 recovery；说明“恢复”已经是独立评测维度，但都需要仿真/额外数据/人类接管，不适合我们“只有 32 任务成功演示 + 180 秒”的约束。

所以本轮不是再喊“更大的 VLA”，而是把上一轮的 **SPA-VLA + RPSM** 蒸馏成一个更小、更硬的东西：

> **GVSM 3.1（Grasp-Verified State Machine）：把“抓没抓住”从一个隐含假设，变成一个由 ECA（期望闭合孔径）+ Lift-and-Watch + 通用相位状态机共同验证、可定向修复的状态。**

### 0.3 想法如何收敛：从 5 个 P0 砍到 3 个押注

上一轮有 5 个 P0（SPA-VLA、RPSM、Portfolio、Compliance、Endurance），每个都“重要”，但不像一个能赢的组合。本轮用“**边际成功率 / 成本**”做了一次蒸馏：

| 上一轮 | 本轮处理 | 原因 |
|---|---|---|
| SPA-VLA 全量 mask 头 + 16 part queries | **降为 SPA-Lite**：只保留 8–12 个 part queries 的 centroid/affordance/descriptor，mask 只做离线教师 | mask 推理成本高；数据探针显示瓶颈在“接触状态”，不在“部件轮廓” |
| RPSM 独立记忆模块 | **并入 GVSM 的 belief/FSM** | 可逆状态本来就该住在状态机里；单独一个 memory 头既难训又难解释 |
| Task Portfolio Optimizer | **保留为支撑**，不作为主创新 | 它决定“先修哪个任务”，但不直接提高单任务成功率 |
| Compliance Compiler | **保留为支撑**，不作为主创新 | 防归零必要，但不是差异化 |
| Endurance Governor | **保留为支撑**，不作为主创新 | N 端口/长时稳定是工程门槛，不是研究卖点 |
| Waist/Pivot | **P2**，默认静态 | 成功率优先；腰部运动带来平衡/外参风险 |
| 世界模型/仿真/在线 RL | **P3**，暂缓 | 算力/资产/规则不确定；先把真实数据用尽 |
| “高地板/首点优先” | **删除** | 首点只影响步骤分；成功率才是第一目标 |

新的三个押注：

- **P0-A：GVSM 运行时验证层**（2 周，低风险，先做）。它不需要重训模型，先包一个强基座；用 ECA + Lift-and-Watch + 通用 FSM 抓“空抓/掉物/放偏/撤销”。这是最便宜的 +成功率 手段。
- **P0-B：PC-VLA（Phase-Conditioned VLA）**（4–6 周，中风险）。把相位头、抓取结果头、ECA 头做进**同一个 checkpoint**；动作头 cross-attend 到相位/部件 token；用弱相位标签 + 反事实增广训练。这样 FSM 不是外挂规则，而是模型自己的先验。
- **P0-C：CSM-CGA 数据引擎**（2–3 周，低风险）。从 33k 成功演示里挖 close/open/regrasp/slip 事件，构造“对象特异的期望孔径”和“空抓/掉落/撤销”增广；这是 P0-A/P0-B 的训练燃料，也是别人不容易快速复制的数据资产。

支撑项：SPA-Lite（部件可供性）、Undo Repair（撤销修复）、PGCR（相位门控的笛卡尔残差）、Bimanual Phase Coupling（双臂相位耦合）、Compliance/Endurance/Portfolio。

### 0.5 为什么这版比上一轮更可能赢

- **对准失败模式**：上一轮赌“部件分割能提升泛化”；本轮先用真实数据证明“孔径是对象特异的、且单独不可判定”，于是把赌注下在**验证 + 修复**，而不是“更细的分割”。
- **对准评分口径**：GVSM 是**跨任务**的；它不需要为 32 个任务各写一套，而是在所有“抓-搬-放”任务上同时降低空抓/掉物/放偏。一个机制抬高 32 个任务的平均成功率，比在 3 个任务上刷 10pp 更划算。
- **对准单模型规则**：PC-VLA 是一个 checkpoint；ECA/phase/grasp 都是头；FSM 是运行时 supervisor，不是第二个策略。相比 FLARE 的在线 MLLM、CommitFlow 的额外 correction policy，我们更轻、更合规。
- **对准 180 秒**：GVSM 的恢复是有界的（最多 2 次重抓、20 秒恢复预算），不会把一次失败拖成超时。
- **对准 human 干扰**：状态谓词允许回退；这是官方备注里最容易被纯 BC 忽略的轴。

### 0.6 一句话押注

**把“抓没抓住”从一个隐含假设变成一个可验证的状态：用对象特异的期望闭合孔径 + 抬升-注视验证 + 通用相位状态机，在单模型内做定向修复；这比再训一个更大的 VLA 更可能抬高 32 任务的平均成功率。**

# RUBICON 4.0 — GVSM 3.1：把“抓取”变成可验证状态

> 本轮增量：复核榜单/规则/接口；对 5 个任务做真实夹爪闭合签名探针；读 2026 年 commitment/recovery/memory 近邻；把上一轮 5 个 P0 蒸馏为 3 个押注（GVSM / PC-VLA / CSM-CGA）。所有外部信息检索日期 **2026-10-23**（除特别注明）。

## A. 结论

1. **公开榜仍不可用**：`leaderboard.html` 写“即将发布”，前端脚本随机填 8 行；`runs.html` 的 256 条记录点进详情是“测试视频占位”。因此“榜首 29.7%”只能当难度先验，不能当真实排名或方案证据。真正可分析的是被点名模型的论文主张。
2. **本轮最硬的新证据来自数据本身**：夹爪闭合孔径是**对象/部件特异**的（tail 分片里中位数从 0.07 到 0.75），且**单独用孔径判断抓取成功会失败**（HangCup AUC 0.261、StackBowls 左臂 0.358）。闭合事件还经常对应 release/place 或多物体，不是失败。结论：**必须把孔径放进相位上下文，并用抬升-注视做硬验证**。
3. **本轮主押注**：**GVSM 3.1（Grasp-Verified State Machine）**——用 ECA（Expected Closure Aperture）+ Lift-and-Watch + 通用相位 FSM + 多线索抓取验证器（MCGV），把“空抓/掉物/放偏/撤销”变成可检测、可定向修复的状态。它先包强基座（2 周、低风险），再蒸馏进 PC-VLA 单模型（4–6 周）。
4. **保留但降级**：SPA-VLA 砍成 SPA-Lite（只保留 part centroid/affordance/descriptor，mask 只做离线教师）；RPSM 并入 FSM；Compliance/Endurance/Portfolio 作为支撑，不再当主创新。
5. **一句话**：**先把“抓没抓住”变成可验证状态，再谈更大的 VLA。**

### B.2 榜单审计

### B.4 提交接口的关键约束

- `metadata`：`control_space`（`joint` 或 `ee`，互斥）、`obs_delta_indices`（决定发送哪些观测 + 时序堆叠）、`image_resize`、`action_chunk_size`、`token`。

## C. 本轮核心新证据：夹爪闭合签名（Closure Signature）

### C.1 方法

从 HuggingFace 直接下载 5 个任务的 tail parquet 分片：

| 任务 | 文件 | episodes | frames |
|---|---|---:|---:|
| HangCup | `data/chunk-000/file-001.parquet` | 324 | 63,999 |
| StackBowls | `data/chunk-000/file-002.parquet` | 143 | 40,550 |
| PlugCharger | `data/chunk-000/file-003.parquet` | 169 | 70,910 |
| OrganizeTools | `data/chunk-000/file-006.parquet` | 76 | 38,278 |
| PourOutMedicine | `data/chunk-000/file-004.parquet` | 173 | 92,277 |

对每只手独立检测 close 事件：

```text
armed = False
for t in episode:
    if action_gripper[t] > 2.5: armed = True
    elif armed and action_gripper[t] <= 0.6:
        close_event.append(t); armed = False
```

对每个 close 事件取：

- `a_close = state_gripper[t + 5]`（闭合后约 0.17s 的实际孔径）；
- `lift = ee_z[t + 40] - ee_z[t]`（约 1.33s 后的抬升高度）；
- `lift > 0.03m` 作为“pick 成功”的代理标签（不是官方 ground truth）。

> 限制：tail 分片不是完整数据集；close 检测阈值是启发式；`lift>3cm` 对 PlugCharger 这类“插入不抬升”的任务不适用；AUC 把所有 close 事件混在一起，包含 release/place，因此不是“抓取分类器”的 AUC，而是“孔径单独可判别性”的下界证据。

### C.2 结果

| 任务（tail） | 臂 | episodes | close 事件 | 孔径中位数 | IQR | lift>3cm | AUC(孔径→lift) |
|---|---|---|---:|---:|---:|---:|---:|
| HangCup | right | 324 | 463 | 0.14 | 0.10–0.22 | 73.4% | 0.261 |
| StackBowls | left | 143 | 176 | 0.25 | 0.19–0.29 | 84.1% | 0.358 |
| StackBowls | right | 143 | 256 | 0.25 | 0.21–0.27 | 94.9% | 0.585 |
| PlugCharger | right | 169 | 86 | 0.33 | 0.32–0.34 | 19.8% | 0.491 |
| OrganizeTools | left | 76 | 107 | 0.66 | 0.61–0.83 | 95.3% | 1.000 |
| OrganizeTools | right | 76 | 50 | 0.75 | 0.73–0.94 | 100% | n/a |
| PourOutMedicine | right | 173 | 1 | 0.07 | 0.07–0.07 | 0% | n/a |

### C.3 四个发现

#### 发现 1：孔径是对象/部件特异的

- 薄杯沿/碗沿：0.14–0.25；
- 插头：0.33（窄而硬）；
- 工具：0.66–0.75（厚柄）；
- 倒药：0.07，且几乎不闭合（主要是拧盖/倾倒）。

**固定阈值不可行**：若把“<0.3 = 空抓”当规则，HangCup/StackBowls 大量成功会被误判；若把“>0.6 = 抓到了”当规则，薄物体全部漏判。必须学 **对象/部件/相位条件化的期望孔径**。

#### 发现 2：孔径单独不足以判断抓取成功

HangCup 的 AUC 只有 0.261，StackBowls 左臂 0.358。原因不是孔径没用，而是**同一个 close 事件在不同相位下含义不同**：

- 抓取：闭合后抬升；
- 挂/放：闭合后释放或水平移动；
- 多物体：同一 episode 的第二次 close 可能是下一个物体；
- 薄物体：成功抓取也接近 0 孔径。

所以 ECA 只能当 **先验/软证据**，不能当硬判决；必须结合 **相位** 和 **抬升-注视**。

#### 发现 3：多 close 事件不一定是失败

- HangCup：198 个 episode 1 次 close，114 个 2 次，11 个 3 次，1 个 4 次；
- StackBowls 右臂：34 个 1 次，106 个 2 次，2 个 3 次，1 个 4 次；
- OrganizeTools 左臂：44 个 1 次，27 个 2 次，3 个 3 次。

这些大多是**多物体/多子目标**（叠 3 个碗、收纳多个工具），不是连续 regrasp。用“close 次数”做失败挖掘会大量误标；必须做 **pick/place 相位分割**：

```text
pick:   close → z 上升 >2cm 且 持续 >0.3s
place:  open  → z 下降/水平远离，且 close 后未抬升
regrasp: close → open <1s，且中间无 place 位移
```

#### 发现 4：有些任务没有 close 相位

PourOutMedicine 的 173 个 episode 里 172 个没有 close 事件；夹爪保持张开，任务是拧盖/倾倒。状态机不能假设“所有任务都是抓-搬-放”，必须有：

- `MANIPULATE`（拧、转、推、拉）；
- `POUR`（倾倒）；
- `INSERT`（插入，可能不抬升）；
- `HANDOVER`（双手交接）。

这也是为什么 **相位头要从数据里学**，而不是写死 8 个抓取阶段。

### C.4 对设计的直接约束

1. **ECA 必须是 `f(part, object, phase, view)`**，不是全局常数。
2. **MCGV 必须是多线索**：孔径先验 + 腕部相对运动 + 孔径稳定性 + 头部目标区域。
3. **FSM 必须能处理“无 close”任务**：相位集合包含 MANIPULATE/POUR/INSERT，且允许 `APPROACH → MANIPULATE` 跳过 CLOSE。
4. **失败挖掘必须做相位分割**：不能把第二次 close 当失败。
5. **薄物体要特殊处理**：ECA 方差大时，降低孔径权重，提高腕部运动/视觉权重。

### D.2 共同瓶颈

1. **语义泛化 ≠ 物理承诺**：模型知道“应该把杯子挂到钩上”，但不知道“现在夹爪里到底有没有杯子”。CommitFlow 把这一点总结为 semantic commitment vs physical condition 的 mismatch，并在 RoboTwin 上把 π0.5 从 53.2% 提到 75.9%（+22.7%）。这是本轮方向的最强外部证据。
2. **成功-only 演示的偏差**：演示里“夹爪闭合”几乎总对应“抓到了”，模型学到的是相关性，不是因果。测试时空抓/滑移/人手干扰会打破相关性。Pseudo-tactile 论文（2503.23835）明确把它称为 **gripper state ambiguity**。

5. **恢复数据稀缺**：成功演示多，失败/恢复少；FLARE/Recova/Kintsugi 都要额外失败数据、仿真或人类接管。我们需要 **从成功数据里挖失败** 的便宜方法。

## E. GVSM 3.1：抓取验证状态机

### E.1 设计原则

1. **单模型合规**：任务决策由一个 checkpoint 产生；ECA/phase/grasp/predicate 都是头；FSM 是运行时 supervisor（代码），不是第二个策略。
2. **不用 task id**：只用语言 + 4 路图像 + proprio。
3. **不写死任务轨迹**：恢复动作由 VLA/相位头生成，或由通用笛卡尔原语参数化；没有 32 套坐标。
4. **有界恢复**：最多 2 次 re-grasp、20s 恢复预算、全局 170s watchdog；超过则安全停止。
5. **可回退**：状态谓词允许 `true → false`；检测到撤销只修复被撤销的子目标。
6. **多线索**：孔径是软先验，腕部运动/视觉是硬证据；不把任何单一信号当真理。

### E.2 相位集合与转移

```text
IDLE
  → APPROACH        接近目标部件
  → ALIGN           腕部视觉伺服到预抓取位姿
  → CLOSE           闭合夹爪
  → VERIFY_GRASP    ECA + MCGV + 短抬升
  → LIFT            抬升 2–3cm
  → TRANSPORT       搬运到目标区域
  → PLACE           下放/对位
  → VERIFY_PLACE    目标区域检查
  → RELEASE         张开
  → DONE            子目标完成

旁路：
  APPROACH → MANIPULATE   拧/转/推/拉（无 close）
  APPROACH → INSERT       插入（可能不抬升）
  APPROACH → POUR         倾倒
  any      → RECOVER      空抓/掉物/放偏/超时/撤销
  DONE     → APPROACH     多物体任务的下一子目标
```

允许的反向/恢复转移：

```text
VERIFY_GRASP → ALIGN      空抓：换偏移/角度重试
VERIFY_GRASP → RECOVER    连续两次空抓：换抓取策略或安全停止
LIFT → RECOVER            滑移/掉物
VERIFY_PLACE → PLACE      放偏：重新对位
DONE → RECOVER            撤销：只修复被撤销的子目标
TRANSPORT → APPROACH      掉落：重新抓取
```

### E.3 ECA：Expected Closure Aperture

**定义**：给定当前部件 token、腕部/头部图像、EE 位姿、相位，预测“如果这次抓取成功，夹爪最终会闭合到多少”。

```text
â_t, σ̂_t = f_ECA( z_part, I_wrist, I_head, p_ee, φ_t )
```

训练（成功演示 + 高置信帧）：

```text
L_ECA = Σ_t [ (a_t − â_t)^2 / (2 σ̂_t^2) + 0.5 log σ̂_t^2 ]
```

推理：

```text
s_t = |a_t − â_t| / σ̂_t
```

- `s_t` 大且相位在 `CLOSE/VERIFY_GRASP` → ECA 认为“闭合得不对”；
- 但 ECA 只是 **软证据**；薄物体 `σ̂` 大，权重自动降低；
- 如果 `σ̂` 很小但对象是未见过的薄物体，MCGV 的腕部运动线索会覆盖 ECA。

**为什么不用固定阈值**：C.2 的表已经证明孔径中位数从 0.07 到 0.75；固定阈值必然在另一类任务上错。ECA 学的是“这个部件应该闭合到多少”，不是“小于多少算空”。

**ECA 的训练目标不是“抓取成功分类”，而是“孔径预测 + 不确定性”**。这让它能在没有负样本的情况下，用预测误差做异常检测；负样本只用于校准 MCGV。

### E.4 Lift-and-Watch：腕部相机是免费的“触觉”

关键观察：**腕部相机和夹爪一起运动**。如果物体被抓住并抬起，它在腕部图像里近似**静止**（相机和物体一起动）；如果没抓住，物体会留在桌面/下滑，在腕部图像里**明显移动**。

```text
# 在 VERIFY_GRASP/LIFT 阶段
c0 = part_centroid(I_wrist, t0)
抬起 2–3cm，等 0.3s
c1 = part_centroid(I_wrist, t1)
d  = || c1 − c0 ||_2          # 归一化到图像尺寸
grasped = d < τ_d              # 物体跟着夹爪走
```

- `τ_d` 用成功演示校准（例如图像宽度的 2–4%）；
- 如果部件被夹爪遮挡：改用 **头部视角 + 物体相对 EE 的位移**；
- 如果物体透明/反光：用 **孔径稳定性**（抬起前后 `a` 变化 < 阈值）作为 fallback；
- 这个测试只需 0.3s，远小于 180s 预算。

**为什么这比“看夹爪闭没闭”强**：夹爪闭合是二值/连续位置，空抓和薄物体抓取都可能接近 0；但“物体是否跟着腕部相机走”是物理事实，且不需要力传感器。

### E.5 MCGV：多线索抓取验证器

把 ECA、Lift-and-Watch、孔径稳定性、视觉存在性融合成一个小验证器（逻辑回归/2 层 MLP，作为 checkpoint 的一个头，或规则式）：

```text
c1 = −s_ECA                          # ECA 负 z-score
c2 = −d_lift                         # 腕部相对位移（越小越像抓住）
c3 = −|a_after − a_before|           # 抬起前后孔径变化（越小越稳）
c4 = 1[part_visible_in_wrist]        # 部件可见性
c5 = 1[object_in_target_region]      # 放置阶段才有

P_success = σ( w0 + Σ wi ci )
```

- 训练标签：`pick` 段且 `lift>3cm` 且腕部相对位移小 → 正；空抓/未抬升/滑移 → 负；
- 负样本从 CSM-CGA 挖（见 G）；
- 推理阈值按任务/相位校准，但**不按 task id 硬编码**；用相位 + 部件类别。

### E.6 Place / Undo 验证

**Place**：

```text
release 后 0.5s：
  - 物体质心在目标区域 mask/box 内；
  - 夹爪孔径 > 打开阈值；
  - 物体在腕部图像中离开夹爪（不再跟随）。
```

**Undo**：

维护谓词向量 `b_t`（每个谓词一个概率）：

```text
in_hand, on_hook, inserted, cap_off, zipped, folded,
stacked(k), sorted(bin), in_box, locked, lid_closed
```

- 谓词来自 part token + 几何关系 + 相位；
- 如果 `b_k` 从 >0.8 掉到 <0.2，且不是机器人自己的动作造成的 → 判为外部撤销；
- 用 **动作残差** 区分“机器人自己碰倒”与“人手撤销”：
  ```text
  r_t = || Δp_object_observed − Δp_object_expected(action) ||
  ```
  残差大且方向与 EE 运动不一致 → 外部干扰；
- 只修复被撤销的谓词 `k`，不重跑全程；修复顺序按依赖图（例如拉链必须先对齐拉头）。

### E.7 FSM 伪代码

```python
class GVSM:
    def reset(self):
        self.belief = Belief()          # phase posterior + predicates
        self.retries = 0
        self.t0 = now()

    def act(self, obs):
        z = self.model.encode(obs)       # part tokens + phase features
        phase = self.model.phase_head(z, self.belief)
        phase = self.fsm.constrain(phase, self.belief, self.guards(obs))

        if phase == CLOSE:
            self.close_sig = self.model.closure_monitor(obs)
        if phase == VERIFY_GRASP:
            p = self.model.mcgv(self.close_sig, obs, z)
            if p < 0.5:
                self.belief.mark_failed("grasp")
                phase = RECOVER
        if phase == LIFT:
            if not self.lift_watch(obs):
                self.belief.mark_failed("slip")
                phase = RECOVER
        if phase == VERIFY_PLACE:
            if not self.place_check(obs):
                phase = RECOVER
        if self.undo_detector(obs):
            phase = RECOVER

        if phase == RECOVER:
            if self.retries >= 2 or now() - self.t0 > 170:
                return self.safe_hold()
            self.retries += 1
            phase = self.choose_repair(self.belief)   # ALIGN/PLACE/APPROACH

        self.belief.update(phase, obs)
        return self.model.action_head(z, phase, self.belief)
```

### E.8 单模型合规说明

- 一个 checkpoint 包含：backbone、part head、phase head、ECA head、MCGV head、action head。
- 运行时**不加载** SAM3/PartSAM/第二个 VLM/在线 LLM；教师只离线。
- FSM 是**运行时 supervisor**：只做相位约束、验证门控、安全停止；不包含 32 套任务坐标，不替代模型选择目标。
- 如果规则对“手写控制器”有疑问：把 FSM 降级为 **训练/推理先验**（phase transition prior），所有动作仍由同一个 action head 产生；manifest 里明确声明。
- 不喂 task id；不按任务加载不同权重；不按任务切换模型。

## F. PC-VLA：相位条件化的单模型

### F.1 架构

```text
4 views (head L/R, wrist L/R) + proprio + language
        │
        ▼
VLM backbone（WLA-1.0 / GigaBrain-0.7 / MolmoAct2 / 其他允许底座）
        │
        ├─ 8–12 part queries（cross-attend 到 4 视图 token）
        │     ├─ existence / affordance（grasp, insert, hang, pull, push, rotate, fold, pour, place, open, close）
        │     ├─ 2D centroid（soft-argmax）
        │     └─ descriptor（跨帧/跨视角跟踪）
        │
        ├─ phase head（GRU + 转移先验）
        │     └─ 相位 posterior q_t ∈ Δ^P
        │
        ├─ ECA head / MCGV head
        │
        ▼
action head（FiLM 相位嵌入 + cross-attend part tokens + proprio）
        │
        ▼
action chunk（双臂 joint 或 EE + grippers + pivot）
```

关键点：

- **part queries 共享**，不按任务分组；任务差异由语言和观测决定。
- **相位嵌入用 FiLM 调制** action head 的中间层，计算量小；不用为每个相位单独一个 expert。
- **RECOVER 是一个可学习的相位 token**，不是外部脚本；模型从增广数据里学“空抓后怎么退、怎么重对位”。
- **不输出 mask**（推理时）；mask 只作为离线教师的辅助监督，降低部署成本。

### F.2 弱相位标签

| 相位 | 规则（训练标签） |
|---|---|
| APPROACH | gripper open，EE 朝部件质心移动，距离减小 |
| ALIGN | EE 速度低，部件质心在腕部图像中心附近，gripper open |
| CLOSE | gripper command 从 >2.5 降到 <0.6 |
| VERIFY_GRASP | close 后 EE 速度低，持续 0.2–0.5s |
| LIFT | close 后 EE z 上升 >2cm |
| TRANSPORT | EE 水平速度高，物体在腕部图像中相对静止 |
| PLACE | EE z 下降/接近目标区域 |
| RELEASE | gripper command 从 <1.0 升到 >2.5 |
| VERIFY_PLACE | release 后 0.3–0.8s |
| MANIPULATE | 无 close，但 EE 姿态/waist 变化，部件在手中 |
| POUR | 无 close，腕部/瓶身倾角变化 |
| RECOVER | 失败检测/撤销/重试段（增广数据） |

- 用 **HSMM/change-point** 平滑硬标签，得到软标签；
- 对 PourOutMedicine 这类无 close 任务，用 EE/waist 变化 + 语言子目标做弱标签；
- 相位标签噪声大，所以 `L_phase` 用 label smoothing + 软标签，不用 one-hot 硬 CE。

### F.3 损失

```text
L = L_action
  + λ_ph  * L_phase        # 软标签 CE / KL
  + λ_g   * L_grasp        # BCE（MCGV）
  + λ_eca * L_ECA          # heteroscedastic NLL
  + λ_pr  * L_predicate    # BCE（可选）
  + λ_tmp * L_temporal     # 正/反向片段对比（undo）
  + λ_div * L_diversity    # part query 多样性（防坍塌）
```

- `L_action`：按底座选择 flow matching / diffusion / CE；不改底座动作头结构，只加 FiLM/cross-attention。
- `L_temporal`：同一段成功轨迹 vs 反向播放片段，学习 `progress_delta`（+1/0/−1）。
- `L_predicate` 只在有可靠谓词标签时使用；没有就关掉，避免噪声。

### F.4 反事实增广

| 增广 | 做法 | 目的 |
|---|---|---|
| 空抓（横向/高度偏移） | 在抓取段把 EE 目标平移 1–2cm / 抬高 1cm， kinematic replay | 让模型见“闭合但没抓到” |
| 腕部图像平移 | 对腕部图像做 5–10% 平移/裁剪，配对原动作 | 模拟对准误差，低成本 |
| 闭合截断 | 在 close 前 0.1–0.2s 强制 close | 模拟过早闭合 |
| 自由空间闭合 | 从其他 episode 挖“远离物体时 close”的孔径轨迹 | 提供真实 empty-close 签名 |
| 反向片段 | 反向播放成功轨迹最后 2–5s | 学习 undo/回退 |
| 物体移除 | 用 SAM3 离线 mask 掉物体，inpaint 或黑块 | 学习“找不到物体→安全停止” |
| 扰动-桥接 | 在相位边界加小扰动，再拼接回原轨迹 | 学习局部恢复（FLARE 思路） |

> 注意：kinematic replay 没有物理引擎，图像不会完全匹配；因此这些负样本只用于 **辅助/低权重**，最终用真机 20–30 trials 校准。不要把它们当 ground truth。

### F.5 推理

```text
q_t = phase_head(z_t, belief_{t-1})
q_t = constrain(q_t, FSM_prior, guards_t)
phase_t = argmax q_t
a_t = action_head(z_t, phase_t, belief_t)
```

- FSM prior 是一个稀疏转移矩阵；非法转移概率置 0（例如 `LIFT → PLACE` 不允许，必须先 TRANSPORT）。
- 如果 MCGV/undo 触发，强制 `phase_t = RECOVER`，并给 action head 一个 `RECOVER` embedding。
- 恢复动作有界：最多 2 次 re-grasp；每次 5–10s；总恢复 <20s。

### F.6 消融

| 实验 | 变量 | 目的 |
|---|---|---|
| A0 | 基座 VLA | 基线 |
| A1 | + GVSM（规则/ECA） | 验证层单独价值 |
| A2 | + PC-VLA phase head（无 ECA） | 相位条件化价值 |
| A3 | + ECA | 期望孔径价值 |
| A4 | + Lift-and-Watch | 腕部验证价值 |
| A5 | + Undo Repair | 撤销修复价值 |
| A6 | + part tokens（SPA-Lite） | 部件表示价值 |
| A7 | 固定阈值 vs ECA | 证明不是阈值调参 |
| A8 | 无 task id vs 有 task id | 证明不是靠 ID 过拟合 |
| A9 | oracle phase / oracle ECA | 上限，判断是否值得继续投入 |

## G. CSM-CGA：闭合签名挖掘 + 反事实抓取增广

### G.1 事件挖掘

对每个 episode、每只手：

1. 检测 close/open 事件（C.1 的阈值 + 迟滞）。
2. 用 EE z / 水平位移 / gripper 状态切分 `pick`、`place`、`regrasp`、`slip`。
3. 统计：
   - `a_close`：close 后 0.17s 的实际孔径；
   - `closure_duration`：command 从 >2.5 到 <0.6 的时间；
   - `lift_0.5s` / `lift_1.3s`；
   - `aperture_delta`：抬起前后孔径变化；
   - `time_to_next_open`。
4. 按任务/臂/部件聚类，得到 **孔径分布**；用 GMM/KMeans 找“薄/中/厚/无闭合”四类。
5. 用 **pick/place 分割** 后的标签训练 ECA/MCGV；不要把所有 close 混在一起。

### G.2 从成功数据里挖负样本

成功-only 演示里仍然有可用负样本：

- **free-space close**：close 时 EE 离桌面物体很远（z 高/腕部无物体）→ 真实 empty close；
- **early close**：close 发生在接近段，随后重新 open → 过早闭合；
- **regrasp**：close → open <1s，且没有 place 位移 → 第一次可能失败；
- **slip**：抬起后孔径增大 >0.2，或物体在腕部图像中下滑；
- **place miss**：release 后物体不在目标区域（可用头部视图 + 目标区域检测）。

这些标签有噪声，用 **PU learning / positive-unlabeled**：

```text
正样本：pick 且 lift>3cm 且腕部相对位移小
未标注：其他 close（可能是 release/place/多物体）
负样本：free-space close / early close / slip（高置信）
```

训练 MCGV 时，未标注样本给低权重或视为负样本的软标签；用 **校准集**（真机 100–200 次抓取）调阈值。

### G.3 反事实增广

见 F.4。重点是 **真实 empty-close 轨迹**（free-space close）比合成图像平移更可靠；图像平移只做辅助。

### G.4 质量控制

- 人工抽检 1–2k 帧，标 close/pick/place/regrasp；
- 计算事件检测的 precision/recall；
- 按任务留出（leave-one-task-out）验证 ECA/MCGV 的泛化；
- 如果某任务 AUC <0.6，标记为“ECA 不可靠”，只用 Lift-and-Watch。

## H. 实验设计

### H.1 离线

| 指标 | 定义 | 目标 |
|---|---|---|
| ECA MAE | 孔径预测平均绝对误差（归一化到 0–5.5） | <0.15 |
| ECA ECE | 预测区间校准误差 | <0.1 |
| MCGV AUC | 抓取成功（lift+腕部运动）分类 | >0.8 |
| MCGV FPR@90% recall | 误报率 | <10% |
| Phase F1 | 帧级相位分类 | >0.75 |
| Pick/place 分割 F1 | 事件级 | >0.85 |
| Undo AUC | 反向片段 vs 正向片段 | >0.85 |

### H.2 Replay / 注入测试

- 从成功 episode 注入：
  - 空抓（把 close 提前/横移）；
  - 滑移（抬起后把物体图像下移）；
  - 放偏（目标区域偏移 2–5cm）；
  - 撤销（反向最后 2–5s / 移除物体）。
- 测 FSM 的检测率、修复决策、误报、时间。
- 这不是任务成功率，只是 **验证器/FSM 的单元测试**。

### H.3 真机

优先 6 个任务（覆盖抓取/插入/双手/撤销）：

| 任务 | 为什么选 |
|---|---|

| T10 PlugCharger | 插入，不抬升；human_4 拔插头（undo） |
| T14 PourOutMedicine | 无 close；human_1 拧回盖子（undo） |
| T16 FoldTowel | 双手、长程；human 翻开毛巾（undo） |

| T27 StackBowls | 薄碗沿、多物体；human 拿走第二个碗（undo） |

- 每任务 10 trials（官方协议）+ 关键任务 20–30 trials（内部）；
- 基线：base VLA；base + GVSM；base + PC-VLA；base + PC-VLA + GVSM；
- 指标：full success、step score、empty-close catch、false alarm、recovery success、time-to-recover、timeout、p99 latency；
- 统计：Wilson 95% CI；paired bootstrap；报告 effect size，不只报 p 值。

### H.4 消融矩阵

见 F.6；额外加：

| 变量 | 说明 |
|---|---|
| ECA only | 只看孔径先验 |
| Lift only | 只看腕部运动 |
| ECA + Lift | 多线索 |
| Fixed threshold | 证明不是调阈值 |
| ECA w/o phase | 证明相位条件化必要 |
| Undo w/o action residual | 证明外部干扰检测必要 |

### H.5 Kill criteria

- ECA 在留出任务上 AUC <0.7 → 降级为软先验，主用 Lift-and-Watch。
- GVSM 在 >2 个任务上让成功率下降（误报/过度干预）→ 加迟滞/降低干预频率。
- PC-VLA 相对 GVSM 的增益 <1.5pp → 保留 GVSM，不投入 PC-VLA 训练。
- SPA-Lite 的 oracle-part 上限 <2pp → 砍掉 part token，回到纯相位/验证。
- 4h soak 成功率漂移 >10pp → 先修部署，不加模型能力。

## I. 任务组合与统计

### I.1 排序数学

```text
S = (1/32) Σ_i (1/10) Σ_j y_ij          # 总平均成功率
Q = (1/32) Σ_i (1/10) Σ_j q_ij          # 总平均步骤分
rank: S desc, then Q desc, then submission_date asc
```

```text
SE(S) ≈ sqrt( (1/32^2) * Σ_i p_i(1-p_i)/10 )
p_i≈0.3: SE ≈ sqrt(0.3*0.7/320) ≈ 2.56pp
95% CI ≈ ±5.0pp
```

| 真实优势 Δ | P(观测排名更高) |
|---:|---:|
| 0.5pp | 55.5% |
| 1.0pp | 60.8% |
| 1.5pp | 66.0% |
| 2.0pp | 70.8% |
| 2.5pp | 75.3% |
| 3.0pp | 79.3% |
| 4.0pp | 86.1% |
| 5.0pp | 91.2% |

**含义**：1–2pp 的榜单差距基本是噪声；想把“排名更高”的概率做到 ~80%，需要约 **3pp** 真实优势；做到 ~90% 需要 ~5pp。不要为单次评测波动改架构。

### I.2 边际价值

```text
一个任务 +10pp  → 总平均 +0.10/32 = +0.31pp
一个任务 +30pp  → 总平均 +0.94pp
全部 32 任务 +2pp → +2.0pp
5 个 0% → 30%    → +4.7pp
5 个 70% → 80%   → +1.6pp
```

**先消灭 0%，再攻 3–5 个短板；不要平均用力。**

### I.3 GVSM 的任务优先级

不要只按“当前成功率”排序；对 GVSM，边际增益近似：

```text
gain_i ≈ P(failure_i) * P(catch_i) * P(recover_i)
```

- `P(failure_i)`：离线/真机的空抓、滑移、放偏、撤销率；
- `P(catch_i)`：MCGV 在该任务的检测率；
- `P(recover_i)`：定向修复成功率；
- 成本 `cost_i`：调试时长、接触密度、任务时长、失败模式数。

高杠杆候选：

| 任务 | 失败模式 | GVSM 作用 |
|---|---|---|
| T10 PlugCharger | 插头没对准/没插进；human_4 拔起 | 插入验证 + 重新对位 + undo 修复 |
| T14 PourOutMedicine | 盖子没拧开/被拧回 | 无 close 相位 + 盖子状态谓词 + undo |
| T16 FoldTowel | 折叠层数错/被翻开 | 折叠谓词 + 局部重折 |
| T19 ZipUp | 拉链头没抓住/被拉开 | 拉头抓取验证 + 重新拉 |
| T27 StackBowls | 碗沿太薄/第二个被拿走 | ECA + lift-watch + 重新叠 |
| T01 HangCup | 杯把/杯沿薄；位置干扰 | 部件抓取 + 重新挂 |
| T25 StoreCups | 多杯子、底座移动 | 多物体相位循环 + 重定位 |
| T09 ToolboxStorage | 4 检查点、工具多 | 长程相位 + 漏步检测 |

### I.4 LPL 协议

- 每任务 10 trials；5 类泛化各 2；
- 离线留出 10–20% episodes，按任务/难度/时长分层；
- 半离线：用官方 `human_1/human_4` 备注构造扰动；
- 真机：优先上表 6 个任务；每任务 5–10 trials（正式 10）；
- 统计：每任务 Wilson 95% CI；总体 bootstrap CI；报告 `E[S]`、`P(S>S*)`、`Var(S)`；
- 不挑成功 trial；所有 trial 落日志。

## J. 合规、部署、接口

### J.1 单模型与“辅助头”边界

| 规则 | 实现 | 测试 |
|---|---|---|
| 单模型全 32 任务 | 一个 checkpoint；part/phase/ECA/MCGV/action 都在同一计算图 | 模型 hash 不变；任务切换日志 |

| 180s | 全局 170s watchdog；最多 2 次 re-grasp；20s 恢复预算 | 注入超时；检查安全停止 |
| N 端口 | 8765…8765+N−1；每端口独立 session；共享模型 | 端口数核对；并发 soak |
| 人机安全 | 工作空间包围盒、速度/关节限幅、人手接近降速/暂停 | 红队；急停；NaN/超限注入 |
| 许可证 | 只用 Apache-2.0/明确许可；SPDX/NOTICE | license scan |

> **风险**：FSM 是手写 supervisor，可能被质疑“不是单模型”。缓解：把 FSM 降级为 phase transition prior；所有动作由 action head 产生；manifest 明确“supervisor 只做安全/验证，不做任务选择”。如果规则更严，PC-VLA 的 phase head 可以完全替代 FSM 的决策，FSM 只保留 watchdog/安全停止。

### J.2 人机安全

- **安全壳**：工作空间包围盒、最大末端速度、最大关节速度、waist/base 限幅、夹爪力上限（若可设）。
- **人机分离**：头部/腕部深度 + 手部检测（规则式/轻量）→ 最小距离；低于阈值降速，低于停止距离暂停。
- **暂停-恢复**：保持姿态、记录 belief；人离开后重观测、重定位、继续；不盲目重跑。
- **watchdog**：推理超时、NaN、动作超限、端口断连 → 清零动作/保持/安全退出。
- **审计**：每 trial 记录时间、动作统计、延迟、安全事件、恢复事件。

### J.3 服务续航

```text
N ports 8765..8765+N-1
   ├─ per-session state（episode、belief、chunk cache；互不共享）
   ├─ request queue / dynamic batcher（按 deadline 聚合）
   ├─ one model server（PC-VLA；所有头）
   ├─ watchdog / health / metrics
   └─ safe fallback（hold / retreat / wait；不切换模型）
```

- 启动预热：dummy 前向、CUDA graph、显存分配；
- 量化：优先视觉 backbone FP8/INT8；动作头保持高精度；
- 缓存：action chunk、part token、静态视觉 token；置信度/人手/大位移触发失效；
- 降级阶梯：chunk 8→12→16；part token 每 2 chunk 更新；分辨率降一档；critical 时 hold/retreat；
- 指标：p50/p95/p99、jitter、超时率、显存、热节流、4h soak 成功率漂移。

### J.4 语义续航

- Part-State Memory：每个部件存 descriptor、3D centroid、last seen、confidence、谓词状态；
- 遮挡：保持 belief，人离开后重检测 + 重投影；不把“看不见”当“消失”；
- 干扰：检测状态回退 → 只修复被撤销的子目标；物体移除 → 重扫描/安全停止；
- 跨阶段：阶段切换不重置记忆；只重置 episode 级状态；
- 指标：30s+ 遮挡后重定位成功率、干扰后恢复率、belief 漂移、false forget rate。

## K. 创新点清单（持续迭代）

### K.1 P0-A：GVSM（Grasp-Verified State Machine）

- **动机**：VLA 把“夹爪闭合”当成“抓到了”；空抓后继续搬运/放置，浪费整次 trial。官方 human 干扰还会撤销已完成子目标，纯 BC 的单调进度头无法处理。
- **与现有方案的差异**：不是第二个 VLM/LLM；用 **对象特异的 ECA** + **Lift-and-Watch** + **相位 FSM** + **MCGV**。相比 CommitFlow 的 semantic commitment monitor，我们用的是 G1 可得的 **夹爪位置 + 腕部相对运动**，不需要额外 correction policy；相比 FLARE 的在线 MLLM，我们延迟低、单模型合规；相比 KEMO 的记忆，我们验证物理状态并允许回退。
- **技术可行性**：高。只用 API 已有的 4 路 RGB + 夹爪位置 + EE pose；不需要力/电流；可包任意基座 VLA。
- **所需资源**：1 张 GPU 做基座推理；现有 33k episodes；2 周工程；真机 6 任务 × 10 trials。
- **落地步骤**：
  1. 跑 C.1 的全量 close/open 事件统计；按任务/臂/相位建孔径分布；
  2. 训练 ECA（heteroscedastic regression）+ MCGV（逻辑回归/2 层 MLP）；
  3. 实现 FSM + 有界恢复 + watchdog；
  4. 离线 replay 注入空抓/滑移/放偏/撤销，调阈值；
  5. 真机 6 任务 A/B：base vs base+GVSM；
  6. 全 32 任务 LPL。
- **风险与缓解**：薄物体/遮挡误报 → ECA 方差门控 + Lift-and-Watch fallback；多 close 事件误判 → pick/place 相位分割；规则质疑 → FSM 降级为 prior + manifest 声明；恢复过头 → 最多 2 次/20s。

### K.2 P0-B：PC-VLA（Phase-Conditioned VLA）

- **动机**：基座 VLA 不知道“现在该验证还是该重抓”，也没有恢复动作；GVSM 的规则干预在复杂任务上可能太硬。
- **与现有方案的差异**：相位头 + ECA 头 + MCGV 头进**同一 checkpoint**；action head 用 FiLM/cross-attend 到相位/部件 token；用弱相位标签 + 反事实增广训练；FSM 只做转移先验/安全门控。相比 S²-VLA 的隐式 belief，我们的相位是离散、可约束、可验证的。
- **技术可行性**：中。需要微调 3.5B–6B；相位标签有噪声，但量大、可平滑。
- **所需资源**：8×A100/H100，1–2 周；33k episodes；教师/增广管线；推理 1×H100/L40S（4 视图 6B 需实测）。
- **落地步骤**：
  1. 用 F.2 规则 + HSMM 生成软相位标签；
  2. 在 WLA/GigaBrain 上加 part/phase/ECA/MCGV 头；
  3. 联合训练 action + phase + ECA + MCGV；
  4. 反事实增广（F.4）；
  5. 消融 A0–A9；
  6. 与 GVSM 组合，真机验证。
- **风险与缓解**：相位坍塌 → 多样性损失/软标签/可视化；标签噪声 → 低权重 + 置信度门控；算力不足 → LoRA/部分微调；增益不足 → 保留 GVSM，砍 PC-VLA。

### K.3 P0-C：CSM-CGA（Closure-Signature Mining + Counterfactual Grasp Augmentation）

- **动机**：成功演示没有负样本；但夹爪轨迹里有大量“空抓/滑移/重抓/自由空间闭合”线索。没有负样本，ECA/MCGV 学不好。
- **与现有方案的差异**：不依赖仿真/人类接管；从 33k 成功 episodes 里挖 **free-space close / early close / regrasp / slip / place miss**；用 PU learning + 图像空间反事实；构造 **对象特异的孔径分布**。
- **技术可行性**：高。只需要 parquet + 视频；事件检测是规则式的；PU learning 成熟。
- **所需资源**：数据管线 + 1–2 张 GPU；2–3 周；人工抽检 1–2k 帧。
- **落地步骤**：
  1. 全量事件挖掘 + 统计；
  2. 按任务/臂/部件聚类孔径；
  3. 挖高置信负样本；
  4. PU learning 训练 MCGV；
  5. 反事实增广；
  6. 留出任务验证 + 真机校准。
- **风险与缓解**：合成负样本不真实 → 只用高置信真实负样本，合成样本低权重；事件检测误差 → 人工抽检 + 迟滞；任务不平衡 → 分层采样。

### K.4 P1-A：SPA-Lite（部件可供性 token）

- **动机**：抓杯把 vs 抓杯身；未见物品需要部件级泛化；纯物体中心不够。
- **与现有方案的差异**：只保留 8–12 个 part queries 的 centroid/affordance/descriptor；**推理时不输出 mask**；SAM3/PartSAM 只做离线教师。相比上一轮的全量 mask 头，算力/风险大幅下降。
- **技术可行性**：中。教师分割对小部件/透明物体有噪声；需要多视角/腕部。
- **所需资源**：教师标注 10–30 万关键帧；8 卡 2–4 天；人工验证 1–2k 帧。
- **落地步骤**：教师管线 → 蒸馏 → 消融（oracle part vs learned）→ 与 PC-VLA 联合。
- **风险与缓解**：教师噪声 → 置信度门控/多视角；part query 坍塌 → Hungarian + diversity loss；不提升 full success → kill（oracle 上限 <2pp）。

### K.5 P1-B：Undo Repair（撤销检测与定向修复）

- **动机**：官方 `human_1/human_4` 大量是撤销（T14 拧回、T16 翻开、T19 拉开、T27 拿走第二个碗、T10 拔起插头）。
- **与现有方案的差异**：谓词允许 `true→false`；用 **动作残差** 区分机器人自己碰倒 vs 人手撤销；只修复被撤销的子目标，不重跑全程。
- **技术可行性**：中。需要 part/object 状态跟踪；遮挡时 belief 保持。
- **所需资源**：part token + 谓词标签；合成 undo；真机脚本化人手。
- **落地步骤**：定义 8–12 个通用谓词 → 训练谓词头/规则 → 动作残差检测 → 依赖图修复 → 真机测试。
- **风险与缓解**：误报 → 时序平滑/迟滞；遮挡 → 多视角/保持 belief；官方协议未知 → 被动检测 + 短停，不做长等待。

### K.6 P1-C：PGCR（Phase-Gated Cartesian Residual）

- **动机**：插头/网线/拉链/瓶盖的最后几毫米，端到端关节回归不够准；EE 位姿误差在 1m 处是厘米级。
- **与现有方案的差异**：只在 `APPROACH/ALIGN/VERIFY` 相位加 **±2cm/±5°** 的雅可比残差；其余相位为零；残差由部件 centroid/normal 驱动，不写死轨迹。
- **技术可行性**：中高。需要 G1 运动学/URDF；IK 奇异/关节限位要处理。
- **所需资源**：运动学模型；真机调试；安全限幅。
- **落地步骤**：URDF/雅可比 → 残差控制器 → 相位门控 → 安全壳 → 插入/拉链任务测试。
- **风险与缓解**：IK 奇异 → 阻尼最小二乘；规则质疑 → 残差幅度小、通用、可关闭；碰撞 → 工作空间/速度限幅。

### K.7 P1-D：Bimanual Phase Coupling

- **动机**：T16 叠毛巾、T19 拉链、T27 堆碗、T09 工具箱需要双手协调；单臂相位不够。
- **与现有方案的差异**：每臂独立相位 + 协调模式（independent/lead-follow/handover）；cross-arm attention；不按任务写死。
- **技术可行性**：中。数据有双臂；相位标签可按臂生成。
- **所需资源**：同一批数据；相位标签；训练。
- **落地步骤**：双臂相位标签 → cross-arm attention → 协调模式分类 → 双手任务验证。
- **风险与缓解**：复杂度 → 先只做 6 个双手任务；模式坍塌 → 监督/可视化。

|---|---|---|---|---|---|---|---|

### K.9 P3：暂缓

- 世界模型/视频预测（DreamZero 路线）：算力/延迟/部署成本高；先做轻量辅助（未来 part mask/光流）而非 14B 推理。
- 完整仿真 RL / Real2Sim：资产/规则/时间不确定；先用手头真实数据 + 反事实增广。
- 在线 RL / DAgger：真机样本效率/安全/时间不允许；Recova 的并行工作站我们不具备。
- 运行时 LLM/VLM API：延迟/网络/单模型规则风险；离线编译/蒸馏可以做。

## M. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| ECA 在薄/透明/未见物体上失效 | 高 | 中 | Lift-and-Watch 主判；ECA 只做软先验；方差门控 |
| 多 close 事件误标导致 MCGV 学偏 | 高 | 中 | pick/place 相位分割；PU learning；人工抽检 |
| GVSM 误报导致过度干预 | 中 | 高 | 迟滞/置信度阈值；最多 2 次；A/B 监控 |
| FSM 被质疑不是单模型 | 中 | 高 | FSM 降级为 prior；所有动作由 action head 产生；manifest 声明 |
| PC-VLA 相位坍塌/标签噪声 | 中 | 高 | 软标签 + diversity loss + 可视化；oracle phase 上限 |
| 反事实增广不真实 | 中 | 中 | 只用高置信真实负样本；合成样本低权重；真机校准 |
| 4 路视频/6B 推理 p99 超预算 | 中 | 高 | chunk 8–16；FP8；part token 缓存；动态 batching；降级 |
| 180s 超时 | 中 | 中 | 全局 170s watchdog；恢复预算 20s；安全停止 |
| 人机安全事件 | 低 | 极高 | 安全壳；人手检测；速度限幅；急停；红队 |
| 外部数据/模型规则不允许 | 中 | 高 | 默认挑战数据 + Apache-2.0 底座；准备小模型 fallback |
| 继续依赖占位榜单做决策 | 中 | 中 | 只用 LPL/论文；不引用假分数 |
| 为步骤分牺牲成功率 | 中 | 高 | 先 S 后 Q；首点只做辅助 |

**停止条件**：

- ECA 留出任务 AUC <0.7 → 停 ECA 扩展，转 Lift-and-Watch + 规则 FSM。
- GVSM 在 >2 任务上掉点 → 降低干预频率/加迟滞；仍掉点则只保留安全 watchdog。
- PC-VLA 相对 GVSM <1.5pp → 停 PC-VLA，保 GVSM。
- SPA-Lite oracle 上限 <2pp → 停 part token。
- 4h soak 漂移 >10pp → 先修部署。
