# 第 47 轮（承接第 46 轮 v23；本轮灵感：需求洞察 × 实时控制） · Demand-Insight × Real-Time：潜在需求洞察驱动的实时控制与延迟租约联合保证（五层架构 v11）

> 承接第 46 轮 v23 Memory-Safety-Voice。v23 用 MVR/VAD/SAB 把记忆检索、语音指令与安全绑定串成闭环，但隐含假设 H5：**用户说出的就是用户需要的，且决策链有无限时间做推理**。这两条在 UniBot 实机上同时不成立：语音槽位是潜在需求的噪声投影（用户说“把杯子拿给我”，未必指桌上最近的那个杯子），而机械臂控制环有硬截止期（视觉-决策-执行的 p99 超过约 300ms 就会出现明显顿挫甚至安全回退）。两个灵感词精确命中 H5：**需求洞察**要求系统维护“真实潜在需求”的后验而不是照抄指令；**实时控制**要求把洞察、询问、感知、执行全部纳入统一延迟预算。二者耦合出新问题：**洞察需要花时间买信息，实时控制要求按时闭嘴；如何在硬截止期内做出对潜在需求仍然正确、且可证明安全（或明确 fail-closed）的决策**。

## 0. 直觉与动机

**灵感 1（需求洞察 → 潜在需求后验与主动询问）**
直觉：指令是需求的低带宽投影。用户说“那个红色的”，可能是表达不完整，也可能指代随场景变化。真正的需求 \(D_t\in\Delta(\Omega)\) 只能通过语音、凝视、手势、任务上下文与历史记忆联合推断。洞察不是“听清”，而是“降低后验熵”：当 \(H(D_t)\) 高且一次澄清询问能显著降熵时，系统应主动问，而不是赌。定义洞察增益为后验熵的期望下降 \(I(a)=H(D_t)-E_{o\sim p(\cdot|a)}[H(D_t|o)]\)，这就是需求维度的价值信息（VoI）。

**灵感 2（实时控制 → 延迟租约与 anytime 决策）**
直觉：控制环里“更晚但更好”没有意义。把每个阶段的时间预算写成可失效的延迟租约 \(\ell_r=(D_\varphi,J_{max},\tau_r,f_s,\varepsilon_d)\)，任何阶段超时，其签发的证书立即作废；推理采用 anytime 算法，在截止期处返回“当前最优 + 覆盖半径”。这样实时性不再是工程细节，而是与能量租约并列的根信任条件：能量决定“能不能看”，延迟决定“来不来得及用”。

**灵感 3（耦合 → 洞察-控制的双环与 Pareto 前沿）**
直觉：洞察与控制是对偶的——一个花时间买信息，一个花时间买确定性。统一目标是在硬截止期 \(D_\varphi\) 内最大化“需求匹配度 − 延迟代价 − 风险代价”。若继续推理/询问的边际信息价值低于时间与风险成本，就立即停止并执行；若后验仍高熵且不允许再问，则进入保守动作或 fail-closed。由此得到可度量的 **洞察-延迟 Pareto 前沿**，而不是单点最优。

**架构升级（v11 五层）**：在 v10 四层上新增 **跨切实时控制层 RTL**，并把 L2 上下文层升级为 **需求洞察层 DIR**。根信任层同时持有能量租约 \(\ell_e\) 与延迟租约 \(\ell_r\)；L1 几何层按模态与延迟预算条件化半径；L2 维护需求后验 \(D_t\) 并驱动检索/询问；L3 CAR 增加 deadline guard；L4 DCL 把澄清询问也视为一种“数据采集任务”计入预算。

## 1. 形式化定义（增量：定义 59–64）

**定义 59（潜在需求、表达需求与洞察增益）**
潜在需求 \(D_t\in\Delta(\Omega)\) 为任务真实目标在感知层 \(\Omega\) 上的分布。语音/手势给出表达需求 \(R(v_t)=\mathcal{A}(D_t)+\epsilon_t\)，其中 \(\mathcal{A}\) 为有损表达算子。给定历史观测 \(o_{1:t}\) 与候选主动询问 \(a\)，洞察增益
\[
I(a)=H(D_t\mid o_{1:t})-\mathbb{E}_{o\sim p(\cdot\mid a,o_{1:t})}\big[H(D_t\mid o_{1:t},o)\big].
\]
**洞察充分判据**：\(H(D_t\mid o_{1:t})\le h_\star\) 或 \(I(a)\le c_a\cdot \mathrm{time}(a)\)（再问不划算）。

**定义 60（需求后验的贝叶斯更新与校准）**
\[
p(D_t\mid o_{1:t})\propto p(o_t\mid D_t,a_{t-1})\,p(D_t\mid o_{1:t-1}),
\]
先验由记忆库 \(\mathcal{M}\) 以 \((c_t,B_t)\) 为键检索给出。校准要求：在独立审计集上，对任意名义覆盖 \(1-\alpha_d\)，后验可信集 \(\mathcal{D}_{1-\alpha_d}\) 的经验覆盖率满足 \(|\widehat{\mathrm{cov}}-(1-\alpha_d)|\le \varepsilon_d\)。未校准的自信错误后验是本架构的一等风险。

**定义 61（延迟租约与可调度性）**
流水线阶段 \(i\in\{感知,洞察,绑定,执行\}\) 的最坏执行预算 \(b_i\)，抖动上界 \(J\)。延迟租约
\[
\ell_r=(D_\varphi,J_{max},\tau_r,f_s,\varepsilon_d),\qquad T_{resp}=\sum_i b_i+J.
\]
**实时可行判据**：\(T_{resp}\le D_\varphi\)，且输出新鲜度 \(\mathrm{now}-\text{stamp}\le \tau_r\)，抖动 \(\le J_{max}\)。不可行时按“询问 > 高分辨率感知 > 记忆刷新”的逆序降级，绝不允许静默超时。

**定义 62（联合需求-能量-延迟证书）**
\[
J_t=(P_t,\ell_p,\ell_e,\ell_r,D_t,m_t).
\]
**联合 soundness**：
\[
\Pr\big(X_t\in P_t \mid \omega_t,m_t,\ell_e,\ell_r\ \text{有效}\big)\ge 1-\alpha_p,
\]
且 \(E(t)\ge E_{min}\)，\(T_{resp}\le D_\varphi\)，后验校准成立。任一租约失效 → 证书级联作废 → CAR fail-closed。

**定义 63（洞察-控制联合策略与 anytime 停止规则）**
\[
\max_{a,m,\tau}\ \mathbb{E}\big[U_{ctrl}(D,m)\big]-\lambda_t\tau-\lambda_eP_m\tau-\lambda_r\,\mathrm{Risk}(D)
\]
\[
\text{s.t.}\quad \tau+T_m\le D_\varphi,\ \ E(t+\tau)\ge E_{min},\ \ H(D_t|o_{1:t})\le h_{stop}.
\]
**anytime 停止**：在时刻 \(t\)，若边际信息价值
\[
\Delta I_t=\mathbb{E}\big[U(D_{t+1})-U(D_t)\big]<\lambda_t\Delta t+\lambda_r\Delta \mathrm{Risk}_t,
\]
立即停止并签发当前最佳证书；到达 \(D_\varphi\) 无条件停止。

**定义 64（失效级联顺序）**
\(\ell_r\) 失效优先于 \(\ell_e\) 失效检测（因为超时更常见且可恢复）：超时 → 降低推理精度 → 若仍超时则关闭 Depth/记忆刷新 → 若仍无可用证书则 fail-closed。级联必须是**单调保守**的：后续降级不得放宽已签发的半径。

## 2. 新增产出与既有 IP 升级

**IP-69 DIR（Demand Insight Resolver）**
- 需求后验维护：语音槽位 \(R(v)\)、凝视/手势、任务上下文、记忆先验的因子化融合
- 校准器：分场景/分任务类型的分层共形或温度标定，输出可信集 \(\mathcal{D}_{1-\alpha_d}\)
- 主动询问选择：按 \(I(a)/(c_a\cdot\mathrm{time}(a))\) 排序，受延迟租约约束
- 高熵处置：\(H(D)>h_{stop}\) 且不允许询问 → 保守动作或 fail-closed

**IP-70 RTL（Real-Time Latency-Lease Scheduler）**
- 每阶段最坏执行时间标定 + 抖动上界估计
- 延迟租约签发/续租/撤销，deadline guard 注入总线
- anytime 中断：到点返回 best-so-far 及覆盖半径
- 降级序列执行器：保证单调保守

**IP-71 AEC（Anytime-Elastic Controller）**
- 可中断推理：任意时刻给出 (动作, 证书, 剩余不确定性)
- 截止期安全裕度：用延迟松弛量 \(\mathrm{slack}=D_\varphi-T_{resp}\) 调整 CB 安全边界
- 洞察-控制预算分配：计算/询问/感知共享同一时间账户

**既有 IP 升级**
IP-66 MVR：检索键改为需求后验 \(D_t\) 而非原始语音；命中需同时满足 \(\ell_e,\ell_r\)。
IP-67 VAD：输出从单点 \(R(v)\) 升级为后验 \(D_t\) 与询问建议；槽位置信进入似然。
IP-68 SAB：绑定阈值随后验熵自适应，\(B(v,P_t)\ge\theta_{safe}(H(D_t))\)。
IP-63 ECPS：效用项加入延迟代价 \(\lambda_t\tau\)，与能量联合求解。
IP-61 DCL：澄清询问与超时样本作为采集任务，带时间成本。
IP-62 CCA：新增后验校准红队、截止期注入测试、虚假自信回归。
IP-51 CAR：守卫加入 \(T_{resp}\le D_\varphi\) 与后验校准检查。
IP-45 总线：新增 demand-belief / latency-lease / probe-request / deadline-guard 话题。

## 3. 算法骨架

DIR-AEC 每控制周期：
1. 读 \(\ell_r,\ell_e,c_t,o_t\)，计算 \(T_{resp}\) 与 \(\mathrm{slack}\)
2. 贝叶斯更新 \(D_t\)，查询校准可信集
3. 若 \(H(D_t)>h_{stop}\)：在剩余预算内选 \(I(a)/\mathrm{time}(a)\) 最高的询问；否则跳过
4. 用 \(D_t\) 驱动 MVR/模态效用求解，选择 \(m_t\)（受能量与延迟双约束）
5. anytime 推理至停止规则或 \(D_\varphi\)，签发 \((P_t,J_t)\)
6. SAB 以自适应 \(\theta_{safe}(H)\) 绑定；任一租约失效 → 单调降级 → fail-closed

## 4. 本轮最大风险

**一句话**：需求后验可能“自信地错”——在硬截止期压力下系统会跳过询问、直接以高置信的错误后验驱动实时控制，导致又快又错且证书仍然自洽（soundness 只保证姿态覆盖，不保证需求正确）；因此必须把后验校准覆盖率作为可失效条件，在 \(H(D)\) 或校准审计不达标时强制询问或 fail-closed，并为需求错误单独设安全谓词。

### IP-69 DIR：贝叶斯更新 + 主动询问
```
def dir_update(D_prev, o_t, a_prev, memory_prior):
    # 似然：语音槽位、凝视、手势、上下文分别给出 factor
    lik = voice_likelihood(o_t.voice, o_t.slots)
    lik *= gaze_likelihood(o_t.gaze)
    lik *= gesture_likelihood(o_t.gesture)
    lik *= context_likelihood(o_t.c_ctx)
    prior = mix(memory_prior, D_prev, w=prior_weight(D_prev))
    D = normalize(prior * lik)
    return D

def insight_gain(D, a, o_model, n_mc=64):
    H0 = entropy(D)
    samples = sample_observations(o_model, D, a, n_mc)
    H1 = mean([entropy(bayes_update(D, o, a)) for o in samples])
    return max(0.0, H0 - H1), H0

def choose_probe(D, candidates, slack, cost_time, lam_t, lam_r):
    best = None
    for a in candidates:
        I, H0 = insight_gain(D, a)
        t_a = cost_time(a)
        if t_a + min_stage_budget > slack:      # 延迟租约不可行
            continue
        score = I / (t_a + eps) - lam_t * t_a - lam_r * probe_risk(D, a)
        if best is None or score > best.score:
            best = Probe(a, score, I, t_a)
    return best   # None 表示询问不划算或不可行

def dir_step(D_prev, o_t, slack, calib, cfg):
    D = dir_update(D_prev, o_t, o_t.a_prev, memory_prior(o_t.c_ctx))
    H = entropy(D)
    calibrated = calib.check(D, rho_cal_min=cfg.rho_min)
    if H > cfg.h_stop and calibrated:
        p = choose_probe(D, cfg.probes, slack, cfg.cost_time,
                         cfg.lam_t, cfg.lam_r)
        if p is not None:
            return D, 'probe', p
    if H > cfg.h_stop and not calibrated:
        return D, 'fail-closed', None     # 自信但未校准 -> 不信
    return D, 'ready', None
```

### IP-70 RTL：延迟租约与单调降级
```
def issue_latency_lease(budgets, jitter, D_phi, tau_r, f_s):
    T_resp = sum(budgets.values()) + jitter
    feasible = (T_resp <= D_phi)
    return LatencyLease(D_phi, jitter, tau_r, f_s,
                        feasible, T_resp, stamp=now())

def degrade_once(pipeline, lease):
    # 降级顺序固定：询问 > 高分辨率感知 > 记忆刷新
    for stage in ['probe', 'highres_perception', 'memory_refresh']:
        if pipeline.enabled(stage):
            pipeline.disable(stage)
            lease.budgets[stage] = 0
            return issue_latency_lease(lease.budgets, lease.jitter,
                                       lease.D_phi, lease.tau_r, lease.f_s)
    return None   # 无可降级 -> fail-closed

def rtl_guard(lease, stage, elapsed):
    if elapsed > lease.budgets[stage]:
        return 'timeout'
    if now() - lease.stamp > lease.tau_r:
        return 'stale'
    return 'ok'
```

### IP-71 AEC：anytime 停止与安全裕度
```
def anytime_decide(D, m_t, deadline, lam_t, lam_r, U, cert):
    t = now()
    best = (safe_fallback(), None)
    while now() + dt <= deadline:
        cand = incremental_improve(D, m_t, cert)     # 任意时刻可中断
        if U(cand) - lam_r * risk(cand) > U(best[0]):
            best = (cand, certify(cand))
        dI = expected_info_value(cand) - expected_info_value(best[0])
        if dI < lam_t * dt + lam_r * delta_risk(best[0], cand):
            break
    return best

def adaptive_theta_safe(H, theta0=0.85, kappa=0.5):
    # 需求熵越高，要求绑定概率越高（更保守）
    return min(0.999, theta0 + kappa * H)

def aec_control(D, m_t, lease, U, cert):
    slack = lease.D_phi - (now() - lease.stamp + estimate_remaining())
    theta = adaptive_theta_safe(entropy(D))
    cand, c = anytime_decide(D, m_t, now() + max(0, slack),
                             lam_t, lam_r, U, cert)
    if c is None or safety_bind(c, theta) < theta:
        return 'fail-closed', None
    return cand, c
```

### 全局决策 \(\Pi^+\)（需求-能量-延迟联合）
```
def global_decision_plus(c_t, omega_t, B_t, v_t, M, calib, Q_safe):
    lease_e = current_energy_lease(B_t)
    lease_r = issue_latency_lease(cfg.budgets, cfg.jitter,
                                  cfg.D_phi, cfg.tau_r, cfg.f_s)
    if not lease_e.valid:
        return 'fail-closed', 'energy'
    if not lease_r.feasible:
        nl = degrade_once(cfg.pipeline, lease_r)
        if nl is None:
            return 'fail-closed', 'latency'
        lease_r = nl

    if Q_safe:
        cmd = pop(Q_safe)
        D, status, probe = dir_step(D_prev, cmd.o_t,
                                    lease_r.D_phi - lease_r.T_resp,
                                    calib, cfg)
        if status == 'fail-closed':
            return 'fail-closed', 'uncalibrated_demand'
        if status == 'probe':
            issue_probe(probe.a)
            return 'waiting_probe', probe
        m = mvr_schedule(cmd.c_t, B_t, D, M, calib)   # 用后验做键
        if m is None:
            return 'fail-closed', 'no_modality'
        cand, cert = aec_control(D, m, lease_r, cfg.U, None)
        if cert is None:
            return 'fail-closed', 'deadline_or_bind'
        return cand, 'execute'

    result = mvr_schedule(c_t, B_t, D_prev, M, calib)
    if result is None:
        return 'fail-closed', 'no_modality'
    cand, cert = aec_control(D_prev, result, lease_r, cfg.U, None)
    if cert is None:
        return 'fail-closed', 'deadline_or_bind'
    return cand, 'execute'
```

## 3. 关键推导

**推导 1（贝叶斯后验与最优询问）**
由定义 60，
\[
p(D\mid o_{1:t},a)=\frac{p(o_t\mid D,a)\,p(D\mid o_{1:t-1})}{\sum_{D'}p(o_t\mid D',a)\,p(D'\mid o_{1:t-1})}.
\]
一次询问的期望后验熵
\[
\mathbb{E}[H(D\mid o,a)]=\sum_o p(o\mid a)H\big(p(D\mid o,a)\big),
\]
故最优询问 \(a^\star=\arg\max_a I(a)/(c_a t_a)\) 在“时间成本线性、风险项可加”下与定义 63 一致；若 \(I(a)<c_a t_a\)，询问被支配，应停止。

**推导 2（截止期安全裕度）**
设控制障碍函数 \(h(x)\) 满足 \(\dot h\ge-\gamma h\)。延迟 \(\Delta\) 内最坏漂移为 \(L_h\Delta\)，因此把安全集收紧
\[
h_{\Delta}(x)=h(x)-L_h\Delta,\qquad \Delta=T_{resp}+\mathrm{slack}_{margin}.
\]
只要 \(h_\Delta(x_0)\ge0\) 且每一步在 \(D_\varphi\) 前签发证书，则执行期不越界。这给出 AEC 中“slack 越小、动作越保守”的严格依据：\(\Delta\) 随 slack 增大而减小，收紧量 \(L_h\Delta\) 同步减小。

**推导 3（联合安全概率的并集界）**
设需求后验、姿态覆盖、绑定检查分别以 \(\alpha_d,\alpha_p,\alpha_s\) 失效。若租约有效且执行条件满足，则一次执行的需求-姿态联合违例概率
\[
\Pr(\text{unsafe})\le \alpha_d+\alpha_p+\alpha_s,
\]
由并集界得到。故工程门槛应取 \(\alpha_d,\alpha_p,\alpha_s\le 10^{-3}\)，并保证任一分项不达标即 fail-closed。此界说明“姿态 soundness 无法替代需求正确性”——二者是正交失效源。

## 4. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| DIR 后验更新 | \(O(|\Omega|\cdot|\text{factors}|)\) | \(O(|\Omega|)\) | 校准覆盖成立时可信集覆盖真实需求 |
| 询问选择 | \(O(|\mathcal{A}|\cdot n_{mc}\cdot|\Omega|)\) | \(O(|\mathcal{A}|)\) | 仅选延迟可行且正增益的询问 |
| RTL 租约 | \(O(|\text{stages}|)\) | \(O(|\text{stages}|)\) | \(T_{resp}\le D_\varphi\) 才签发 |
| AEC anytime | \(O(B/\Delta t)\) 截止期截断 | \(O(1)\) 增量 | 到点返回 best-so-far，证书不超时 |
| \(\Pi^+\) 全局 | \(O(|\mathcal{M}|+|\mathcal{A}||\Omega|)\) | \(O(|\Omega|+|Q|)\) | 四重失效门 → fail-closed |

**正确性定理（条件保证）**：给定 (i) 后验在审计集上校准，\(\widehat{\mathrm{cov}}\ge1-\alpha_d-\varepsilon_d\)；(ii) 能量租约与延迟租约在签发时刻均有效；(iii) 执行前 \(B(v,P_t)\ge\theta_{safe}(H(D_t))\)；(iv) 任一降级单调保守。则 \(\Pi^+\) 输出的执行动作要么满足
\[
\Pr(\text{需求-姿态联合安全})\ge1-(\alpha_d+\alpha_p+\alpha_s),
\]
要么在任一门失败时进入 fail-closed，绝不静默执行。证：由 (i)(ii) 得需求与姿态证书有效，由 (iii) 得绑定通过，三者失效事件并集界给出概率；门失败分支由算法显式返回 fail-closed；降级单调性由 IP-70 固定降级序列保证。∎

## 5. 实验设计 E115–E120

| 实验 | 指标 | 门槛 |
|---|---|---|
| E115 需求后验校准 | ECE、Brier、可信集覆盖率偏差 | ECE ≤ 0.05；Brier ≤ 0.15；覆盖率偏差 ≤ 0.03 |
| E116 主动询问效率 | 平均询问次数、需求满足率 | 询问 ≤ 1.5 次/任务；满足率 ≥ 95% |
| E117 实时截止期 | p99 延迟、deadline miss、抖动 | p99 ≤ \(D_\varphi\)；miss ≤ 0.1%；抖动 ≤ \(J_{max}\) |
| E118 洞察-延迟 Pareto | 前沿支配率（相对静态基线） | 前沿在 ≥ 80% 工况支配；平均匹配度 +20% |
| E119 联合安全 | 不安全执行数、fail-closed 正确率、级联单调性 | 不安全 0 起；fail-closed 正确率 100% |

**回退策略**：E115 校准不达标 → 关闭后验驱动、回退 \(R(v)\) 点估计并提高询问频率；E116 询问过多 → 放宽 \(h_{stop}\) 或降低询问成本模型；E117 miss > 0.1% → 缩短预算、提前插入 fail-closed；E119 任一不安全 → 冻结执行并进入全保守模式。

## 6. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 后验“自信地错” | 高 | 分层共形校准 + 未校准即 fail-closed；需求错误单列安全谓词 |
| 询问过多拖垮实时性 | 中 | 询问纳入延迟租约，按 \(I/(c_a t_a)\) 排序，超预算直接跳过 |
| 截止期压力下跳过澄清 | 高 | 高熵且不允许询问时禁止执行，转保守动作或 fail-closed |
| anytime 早停导致证书过宽 | 中 | 覆盖半径随剩余不确定性显式签发，超过阈值即降级 |
| 降级不单调放宽安全边界 | 高 | 固定降级序列 + 单调保守检查器，CCA 注入超时红队 |
| 抖动导致 p99 违约 | 中 | 抖动上界纳入租约；超标触发降级而非硬撑 |

## 7. 本轮最大风险

**一句话**：后验校准只在审计集上成立，分布漂移或截止期挤压会让系统以“已校准”的错误后验快速执行，而姿态证书仍然 soundness 自洽，从而把安全漏洞从几何层转移到语义层；因此必须把需求正确性做成独立可失效谓词（校准覆盖率 + 熵阈值 + 询问预算三者任一不满足即 fail-closed），并持续在线监测校准漂移。
