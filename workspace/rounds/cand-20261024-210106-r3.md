# 第 3 轮（承接第 7 轮状态）· TIGR：意图是查询，配准是证据，排行榜是目标函数

> 检索/复核日期：2026-10-24（UTC）。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮是灵感循环第 3 轮，状态基线为第 7 轮 PILOT-GPR；三个灵感词是「意图识别」「排行榜」「点云配准」。我先核实赛事与榜单的最新状态，再把三个词合成一个判断：**UniBot 的瓶颈不是“看不懂语言”，而是部分可观测与人为干扰下的“短时意图别名（intent aliasing）”——同一帧观测可以对应不同的子任务意图（抓哪个、放哪里、做到第几步、人刚改了什么）；排行榜又是成功率先行、320 trials 的低信号评测，只有能提高整任务成功率的干预才值得做；点云配准是把意图从语言/外观落到几何证据的最便宜算子。** 于是本轮方案 TIGR = 意图晶格 + 意图-目标模板库 + 意图引导配准 + 场景变化检测 + 配准验证收尾 + 排行榜守卫。

> 说明：本文用 [S#] 标注来源，完整 URL/用途见产物区 §12；榜单页上的数字仍是占位，只作弱先验，不作排名依据。

## 0. 本轮先核实：六个事实

### 0.1 排名规则是“成功率先行”的字典序（已核实）

参赛手册 [S1] 明确：

- 32 个任务，每个任务 10 次独立运行；5 类泛化（位置/干扰物/背景/未见物品/人为干扰）各 2 次；
- **实时榜单按 32 个任务的总平均成功率排序；成功率相同才按总平均步骤分排序；仍相同则提交日期较早者靠前**；
- 单次真机执行最大 180 秒，超时记失败，并按执行情况计算步骤分；
- 所有任务须基于**同一模型**完成，不得混合使用多个模型；模型类型不限（VLA/World Model 均可）；
- 选手自行部署，官方通过远程 API 调用；评测在多台机器人上以随机顺序进行。

这修正了第 7 轮把“成功率与步骤分”理解成某种加权综合的隐含假设。正确的目标函数是：

```text
主目标 = 32 任务 × 10 次 = 320 trials 的总平均成功率
次目标 = 总平均步骤分（只在成功率打平时使用）
再次 = 提交日期更早
```

三个直接后果：

1. **终局放置的“闸门”论点更强，不是更弱。** 32/32 任务的成功都以终局步骤为必要条件；终局失败直接抹掉整次 success。
2. **“终局占 39.8% 步骤分”不能直接换成排名收益。** 部分分只在 tie-break 时有用；为了多拿 10 分步骤分而牺牲 1pp 成功率，是错误交易。
3. **统计噪声必须进入决策。** 320 trials、p≈0.30 时总体 SE≈2.56pp；+3pp 只有 1.2 SE，+5pp 约 1.95 SE。2–3pp 的“提升”很可能只是噪声；官方每任务只有 10 次，单任务成功率是 10% 量化的。

### 0.2 榜单仍是占位，“榜首不到 30%”只能当弱先验

- `leaderboard.html` 仍显示「即将发布 / Coming Soon」，但表格里渲染出 8 个模型；榜首 MolmoAct2 为 29.7% / 39.0 [S8]。
- `leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，8 个模型 × 32 任务 = 256 条 `task_metrics` 是脚本生成 [S9]。
- `runs.html` 仍是 256/256 占位；详情页明确写「测试视频占位，后续可替换为真实视频文件」[S10]。

因此：**“榜首不到 30%”与当前页面显示一致，但它不是已核实的真实成绩。** 本轮的论点不依赖这个具体数字：即使真实榜首是 35–50%，任务态估计、终局精度和人为干扰恢复仍然是瓶颈；反之，如果真实榜单发布，必须重跑头部分析。

### 0.3 32 任务 / 94 个评分步骤 / 3200 分；终局是 32/32 的闸门

我复核了 T27 `stack_bowls_three` 与 T10 `plug_charger` 的 `info.json` [S4]，第 7 轮的全量统计保持：

- 32 任务、94 个评分步骤、合计 3200 分；
- **终局步骤合计 1275 分（39.8%）**；
- **32/32 任务的终局步骤都是该任务的最高权重步骤**；
- 18 个任务所有步骤等权；25 个任务终局权重 ≥40；
- 步骤数分布：11 个任务 2 步、14 个 3 步、5 个 4 步、2 个 5 步；
- 难度 12 Easy / 12 Medium / 8 Hard。

T27 的 30/30/40 与 T10 的 30/30/40 都已逐字复核。**终局步是 success 的 AND 闸门，中间步是 step score 的 SUM 部分分；两者错位，必须字典序处理。**

### 0.4 数据：33,276 条、32 任务、2026-10-14 全量；有校准立体，但没有 depth

- HF collection `unibot-v1-challenge-dataset` 当前 32 个数据集，合计 **33,276** 条 episode（官方任务页写 32,000 / 169h，HF 扩容后略高）[S3]。
- HangCup 实测 1,043 条 / 194,564 帧 / 30fps；所有 32 个数据集的 `lastModified` 均为 **2026-10-14** [S5]。
- 四路相机 `head_stereo_left/right` + `wrist_left/right`，480×640；状态含双臂 7+7 关节、EE pose（base/torso 两套）、夹爪、lower_body；**没有 depth 图像**。
- 高位是校准过的立体对：HangCup 的 `camera_params.head_stereo` 给出 `rectified=true`、基线约 **58.25mm**、焦距约 **282px** [S5]。
- 每条任务在 `meta/tasks.parquet` 里有 5 条英文复述；每个任务页还给出 5 个示例 episode [S4]。

立体深度的量级必须算清楚：

```text
Z = f·b / d,   ∂Z/∂d = −Z²/(f·b)
0.5m: d≈32.9px, 1px≈15.2mm, 0.25px≈3.8mm
1.0m: d≈16.4px, 1px≈60.8mm, 0.25px≈15.2mm
```

结论：**0.5–0.7m 的桌面立体点云足够做“对象/容器级”的 6D 粗配准与变化检测，不够做毫米级插入；毫米级交给腕部视觉伺服 + 柔顺控制。** 这决定了 TIGR 的分桶策略，而不是假装点云能包打一切。

### 0.6 提交接口 v2 未变；没有 depth/外参；N 端口；单模型

`unibot_submission` README 仍是 2026-08-21 的 v2（仓库只有 2 次提交）[S6][S7]：

- 观测：4×RGB 480×640、双臂 joint/EE、夹爪、lower_body、单字符串 `observation.language`；
- `metadata` 控制 `control_space`（joint/ee 互斥）、`obs_delta_indices`（选键+堆叠）、`image_resize`、`action_chunk_size`、`token`；
- 评测跨 **N 台机器人**，从 8765 起暴露 **N 个连续端口**；每端口独立、状态隔离；
- **API 不暴露相机内参/外参，也没有 depth**；相机固定安装，标定只能靠数据集参数 + 现场自校准。

这意味着：点云配准必须建立在“高位立体对 + 固定外参假设”上，并且所有几何计算都在我们自己的推理侧完成；接口允许我们裁剪/缩放/堆叠图像，也允许在 `get_action` 里做确定性几何运算。

## 1. 三个灵感词，各钉到一个真问题

### 1.1 意图识别：不是聊天意图，是“短时意图别名 + 指代意图 + 干扰意图”

IntentVLA（HUST，2026）给出了本轮最关键的证据 [S12]：机器人模仿数据是多峰的——相似视觉-语言观测之后可能跟着不同动作 chunk，因为演示者有不同**短时意图、任务相位或近期上下文**；现有 frame-conditioned VLA 只从当前观测和指令推断 chunk，在部分可观测下会在相邻重规划步之间重采样不同意图，导致 **inter-chunk conflict** 与执行不稳。IntentVLA 用近期视觉历史编码一个紧凑的短时意图表示来条件化 chunk 生成，并在 AliasBench（12 个歧义任务）、SimplerEnv、LIBERO、RoboCasa 上改善 rollout 稳定性。

映射到 UniBot，意图至少有四层：

| 层级 | 内容 | 主要证据 | 现有 VLA 的问题 |
|---|---|---|---|
| 任务意图 | 32 个任务中的哪一个 | 语言（32×5 复述） | 通常能对，但不是瓶颈 |
| 指代意图 | 抓哪个物体/放哪个容器/哪个槽位 | 语言 + 几何 | 位置/背景/未见物品一变就错 |
| 相位意图 | 当前在第几步、上一步是否真完成 | 历史 + 谓词 | 跳步、假完成、重复做 |
| 干扰意图 | 人刚移动了什么/撤销了哪步 | 变化检测 | 继续按旧计划执行 |

**现有方案的缺口：意图被纠缠在隐式 token 里，没有一个可查询、可验证、可回滚的后验。** TIGR 把意图做成离散变量，用几何证据去推断它，而不是让 VLM 自由生成一段计划。

### 1.2 点云配准：把“意图”从语言/外观落到几何证据

点云配准在本赛里不是“建稠密地图”，而是**任务相关对象/容器与目标模板之间的局部 6D 对齐**。这条路线有完整的证据链：

- **Imagination Policy**（2024）[S13]：先生成目标点云，再用点云配准把观测点云与“想象的目标”对齐，得到刚体变换来指挥机械臂；把动作推断变成局部生成任务，样本效率极高。
- **G6D**（2026）[S14]：learning-free、几何驱动的 RGB-D 6D 位姿求解器；给定 mask、内参、CAD，模板几何匹配 + 轮廓/深度一致性精化；CPU 可跑，精度-算力可调。
- **RelAfford6D**（2026）[S15]：training-free 的关系 6D affordance 图；从自由指令推断“主交互部件—锚点”的语义拓扑，再提升为精确 SE(3)，用运动学约束 + 闭环跟踪抗扰动。
- **PointMapPolicy**（2025/2026）[S16]：结构化点图 + RGB 的扩散策略，在 RoboCasa/CALVIN 上 SOTA；说明点云几何与 RGB 语义互补。
- **RiEMann**（CoRL 2024/2025）[S17]：SE(3)-等变、无需分割的场景点云模仿学习，5–10 条演示即可，泛化到未见 SE(3) 变换与物体实例。
- **3PoinTr**（2026）[S18]：从人类视频预测全局 3D 点轨迹，压缩成计划 token；平均成功率 79.3% vs 最强基线 52.0%（+27.3pp），说明“3D 运动计划”比纯视频预训练更有效。

这些工作共同支持一个判断：**配准/点轨迹不是感知的装饰，而是把“目标关系”变成“可执行刚体变换”的接口。** UniBot 的特殊性在于：我们没有 CAD、没有 depth、只有校准立体和 33k 演示；所以不能照搬 G6D 的 CAD 管线，而要用**演示目标点云**做模板（Imagination Policy 的思路），用**容器坐标系**做相对表达（OPT 的思路），用**配准残差**做意图似然与变化检测。

配准能同时给出四样东西：

```text
1) 6D 目标位姿 T_B^G          → 给动作专家/伺服
2) 配准 fitness / inlier ratio → 意图后验的观测似然
3) 残差场 r(x)                 → 步骤完成/放置稳定/变化检测
4) 对称性下的多假设            → 杯子/碗/盘子的旋转歧义
```

这四样正好对应 UniBot 的四个失败面：指代、相位、终局精度、干扰恢复。

### 1.3 排行榜：成功率先行、低信号、字典序

排行榜不是“结果页”，而是**目标函数和实验设计**。把 0.1 的规则写成算术：

```text
success = ∏_k z_k            # 所有步骤完成才是 1（AND）
step_score = Σ_k w_k z_k     # 部分分（SUM）
ranking = lex(mean success, mean step_score, −submit_date)
```

统计后果：

- 320 trials，p≈0.30 时总体 SE≈**2.56pp**；+3pp≈1.2 SE，+5pp≈1.95 SE；
- 每任务 10 次，单任务成功率是 **10% 量化**；总榜是 **0.3125pp 量化**；
- **+1 个任务成功 = +3.125pp 总榜**；+2 个任务 = +6.25pp。也就是说，“+3pp”只是多成功一个任务，不能当胜利；“+5pp”约 1.6 个任务，仍然偏噪声；**目标应是 +2 个任务（6.25pp）或一类任务的系统性修复**。
- 步骤分只在 success 打平时决定名次；但 320 trials 下 1–3 个任务的差异本来就在噪声内，所以**步骤分 tie-break 实际会经常发生**。正确策略是：成功优先；在不降低成功概率的前提下，尽量拿步骤分；当成功已不可能时，切到“salvage 模式”最大化剩余步骤分。

排行榜还给出三个策略含义：

1. **不要追占位榜。** 当前 8 个模型/256 条指标是脚本生成；真实榜单发布前，任何“头部方案瓶颈”的分析都只能基于公开论文，不能基于占位数字。
2. **用 rank probability 而不是 mean 选模型。** 320 trials 的均值不确定性很大；应报告 rank 区间/击败中位数的概率，并用配对 bootstrap 或 N-SCORE 做本地比较 [S20][S21][S22]。
3. **提交时机有期权价值。** 规则说成功率/步骤分都相同则提交早者靠前；如果允许多次提交，早交一个强 checkpoint 有 tie-break 优势，但不值得为 2–3pp 的噪声提前交。具体规则（每队可提交几次、保留哪个模型）未核实，标为开放问题。

## 2. 本轮主判断：TIGR

### 2.1 一个更锋利的失败模型

| # | 失败模式 | 表现 | TIGR 对策 |
|---|---|---|---|
| F1 | 指代 grounding 错 | 选错物体/容器/槽位；位置/背景/未见物品轴崩 | 意图晶格 + 目标模板配准 |
| F2 | 相位/意图别名 | 同一观测重采样不同 chunk；跳步、重复、假完成 | 历史意图后验 + 步骤图 + 配准验证 |
| F3 | 干扰未检测 | 人移动物体/撤销步骤后仍按旧计划执行 | 场景变化检测 + 意图回滚 |
| F4 | 终局精度不够 | 插入/堆叠/拉链最后 3cm 失败 | 目标模板配准 + 腕部伺服 + RVS |
| F5 | 长程记忆/遮挡 | 物体移出视野后找不到；容器被挡 | 目标模板 + 参考点云 + 容器系表达 |
| F6 | 评测错配 | 追步骤分、被 2–3pp 噪声误导 | 排行榜守卫 + 成功率先行 + salvage |

F1/F2/F3/F5 都是“任务态/意图”问题，不是“动作生成”问题；F4 是系统精度问题；F6 是目标函数问题。TIGR 主要打前四个，保留 PGL/腕部伺服打 F4，LGV 打 F6。

### 2.2 为什么这比第 7 轮 PILOT 和第 2 轮 T-SLAM 更该做

- **PILOT（第 7 轮）**把火力集中在终局放置，方向对，但仍是“在端到端 VLA 外面加 PGL/OPT/SVL”；它没有解释“为什么模型会选错对象/跳步/被人干扰后不恢复”。TIGR 把终局放置放进一个更大的任务态框架：终局只是意图晶格的一个相位。
- **T-SLAM（第 2 轮候选）**的方向也对（任务态估计），但对象级地图 + 相位 MoE 偏重，且相位 MoE 在 OOD 上未经验证。TIGR 把地图压缩成“意图-目标模板库 + 变化残差”，把相位路由换成意图 token 条件化，把评测从“步骤分字典序”升级为“成功率先行 + rank probability”。这是一次**修剪**，不是推倒重来。
- **头部模型**（MolmoAct2/WALL-OSS-0.5/DreamZero/GigaBrain-0）都在“更大预训练 + 更强语义泛化”上竞争；它们的公开瓶颈是终局精度、任务进度≠成功率、14B 成本、生成数据 gap。**没有人把“可验证的几何任务态”做成一层可插拔的系统。** 这是我们的生态位：不 out-pretrain，out-structure + out-verify。

### 2.3 保留 / 升级 / 新增 / 修剪

| 关系 | 内容 |
|---|---|
| 保留 | WLA-1.0-Base 底座、GPR-VLA（目标残差+可逆信念）、TLE/ACP/GF 数据引擎、AH-TP、Endurance Governor、Compliance Compiler、DebugLoop、FLEET 工程检查单 |
| 升级 | SSG → 意图晶格 IL；PGL → 意图-目标库 IGL；OPT → 意图引导配准 IGR；ICR → 配准不变检索 RIR；SVL → 配准验证收尾 RVS；NRB → 变化检测触发的恢复 |
| 新增 | IGL、IGR、SCD（场景变化检测）、IBF（意图信念滤波）、LGV（排行榜守卫）、rank probability/N-SCORE 评测 |
| 修剪 | 稠密 SLAM/3DGS/NeRF；相位 MoE；per-task LoRA；多模型堆叠；全 32 任务高保真孪生；自由仿真数据；运行时 MPC/RL；布料/拉链/透明全物理；WMA-0 进主路径；大实验室网络作为主路径；步骤分优先目标 |

## 3. 方案轮廓：TIGR-GPR

```text
语言（32×5 复述）
   │
   ▼
IL 意图晶格：任务 × 指代 × 容器/槽位 × 相位 × 干扰
   │
4×RGB + proprio
   │
   ├─ 高位立体 → 任务相关点云（去桌面/聚类）
   ├─ IGL：演示目标模板库（容器系）
   └─ 参考点云（episode 起始）
             │
             ▼
IGR 意图引导配准：top-k 模板 → 6D 目标位姿 + fitness + 残差
SCD 场景变化检测：参考配准残差 → 平移/撤销/遮挡
             │
             ▼
IBF 意图信念滤波：p(step, goal, change | obs, language)
             │  intent token + goal pose + uncertainty
             ▼
GPR-VLA（单一 checkpoint）：目标 z* − 部件信念 b → 残差 r → Action Expert → chunk
             │
             ▼
RVS 配准验证收尾：缓放 → 残差 < τ → 稳定窗口 → nudge/regrasp/retry
             │
             └─► 变化/撤销 → 回滚相位 → 复用 IGL/IGR
```

一句话：**把意图当作查询、把点云配准当作证据、把排行榜当作目标函数；用演示目标模板替代 CAD/2D 锚点，用配准残差同时做意图后验、终局验证和干扰检测。**

## 4. 风险与合规（先立后破）

- **立体噪声/透明物体**：0.5m 处 1px≈15mm，插入类不够；分桶回退到 2D 锚点 + 腕部伺服 + 力/电流，不强行用点云做毫米级。
- **外参假设**：API 不暴露相机外参；用数据集 `camera_params.head_stereo` + `state_d435`/`state_torso` 估固定外参，现场用桌面平面/标定板自校准；失败则退回 2D。
- **对称性**：杯子/碗/盘子有旋转对称；配准必须做 symmetry-aware 多假设，否则会选错 yaw。
- **机器人手臂遮挡/人臂进入**：变化检测要用运动学自模型 mask 机械臂；人臂只当遮挡或干扰，不误判为对象移动。
- **单模型合规**：SGBM/FPFH/RANSAC/ICP/IBF/SCD 都是确定性算法；学习组件只在唯一 checkpoint；不用 SAM/RAFT-Stereo 等第二个模型（若要语义分割，蒸馏进 checkpoint 或用几何聚类）。目标模板库是数据，不是模型，但要在模型卡披露。
- **外部数据**：默认只用官方 33k；实验室数据/仿真数据是否允许仍未核实（手册 2.2 之后未完整抓取），合规开关默认 OFF。
- **调试槽稀缺**：不计分单任务调试只做“假设检验”，不做 A/B 显著性；每个大版本最多 1 槽。
- **统计噪声**：320 trials；目标 +2 个任务（6.25pp）或一类任务修复；不把 2–3pp 当胜利。

## 5. 一句话押注

**把意图当作查询、把点云配准当作证据、把排行榜当作目标函数：用“意图晶格 + 演示目标模板 + 配准残差”构成可验证的任务态估计器，专攻终局成功与人为干扰恢复，而不是继续在单个泛化轴或步骤分上抠点——这是本轮最值得押注的方向。**

## 0. 产物摘要

### 0.1 一句话

**UniBot 的瓶颈不是“看不懂语言”，而是部分可观测与人为干扰下的“短时意图别名”：同一帧观测可以对应不同子任务意图（抓哪个、放哪里、做到第几步、人刚改了什么）；排行榜又是成功率先行、320 trials 的低信号字典序评测，只有能提高整任务成功率的干预才值得做；点云配准是把意图从语言/外观落到几何证据的最便宜算子。TIGR 用“意图晶格 + 演示目标模板库 + 意图引导配准 + 场景变化检测 + 意图信念滤波 + 配准验证收尾 + 排行榜守卫”把这三件事闭成一个环。**

### 0.3 预期收益（可证伪，不把噪声当胜利）

- 排名是**总平均成功率先行**；步骤分只在成功率打平时使用。因此 TIGR 的收益必须体现为“整任务成功”，而不是“步骤分多拿 10 分”。
- 320 trials、p≈0.30 时总体 SE≈**2.56pp**；+3pp≈1.2 SE，+5pp≈1.95 SE。**+1 个任务全成功 = +3.125pp 总榜；+2 个任务 = +6.25pp。** 目标应是“修复一类任务”或“+2 个任务”，不是 2–3pp 的局部抖动。
- 预期分层：指代/相位层 +4–7pp；终局验证层 +3–5pp；干扰恢复层 +3–5pp（human 轴占 20% trials）；三者不独立，保守目标 **+5pp（≈1.6 个任务）**，进取目标 **+6.25pp（2 个任务）**。
- 可证伪点：
  1. 若 IGL/IGR 在刚性放置任务上的离线 6D 目标误差中位数 >1cm 或 >5°，则“演示模板可替代 CAD”不成立，退回 2D 锚点 + 腕部伺服。
  2. 若 IBF 的相位/指代后验在留出任务上比无历史基线低 <3pp，则“意图别名是主要瓶颈”不成立，退回纯 GPR-VLA。
  3. 若 SCD 在官方 human 备注回放上的 AUROC <0.75，则变化检测不足以触发回滚，NRB 只做训练增强，不做在线恢复。
  4. 若调试槽终局成功率 <+10pp，或计分跑总成功率 <+2.5pp（低于 1 SE），则本轮主轴不成立，保留 IGL/IGR 作为感知增强，不宣称任务态突破。

## 1. 事实核对（本轮新增/复核；来源表见 §12）

### 1.1 排名规则是“成功率先行”的字典序（已核实）

参赛手册 [S1][S2] 明确：

- 仅设多任务通才模型赛道；必须用**同一模型**完成全部 32 个任务，不得按任务混合多个模型；模型类型不限（VLA/World Model 均可）。
- 每个任务 **10 次独立运行**；5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰）**各 2 次**。
- **实时榜单按 32 个任务的总平均成功率排序；成功率相同才按总平均步骤分排序；仍相同则提交日期较早者靠前。**
- 单次真机执行最大 **180 秒**，超时记失败，并按执行情况计算步骤分。
- 选手自行部署推理服务；官方只远程调用 API，不提供算力；评测全自动，要求稳定在线。
- 另有**不计分单任务调试通道**（1 个任务、不计入排行榜），需预约时段 [S11]。

写成目标函数：

```text
success(episode) = ∏_k z_k                 # 所有评分步骤完成才是 1（AND）
step_score(episode) = Σ_k w_k z_k          # 部分分（SUM）
ranking = lex(mean_success, mean_step_score, −submit_date)
```

三个直接后果：

1. **终局放置的“闸门”论点更强，不是更弱。** 32/32 任务的成功都以终局步骤为必要条件；终局失败直接抹掉整次 success。
2. **“终局占 39.8% 步骤分”不能直接换成排名收益。** 部分分只在 tie-break 时有用；为多拿 10 分步骤分而牺牲 1pp 成功率，是错误交易。
3. **统计噪声必须进入决策。** 每任务只有 10 次，单任务成功率是 10% 量化；总榜是 0.3125pp 量化。2–3pp 的“提升”很可能只是噪声。

### 1.2 榜单仍是占位，“榜首不到 30%”只能当弱先验

- `leaderboard.html` 仍显示「即将发布 / Coming Soon」，但表格里渲染出 8 个模型；榜首 MolmoAct2 为 **29.7% / 39.0** [S8]。
- `leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，8 个模型 × 32 任务 = 256 条 `task_metrics` 是脚本生成 [S9]。
- `runs.html` 仍是 **256/256 占位**；详情页明确写「测试视频占位，后续可替换为真实视频文件」[S10]。

因此：**“榜首不到 30%”与当前页面显示一致，但它不是已核实的真实成绩。** 本报告的论点不依赖这个具体数字：即使真实榜首是 35–50%，任务态估计、终局精度和人为干扰恢复仍然是瓶颈；反之，如果真实榜单发布，必须重跑头部分析。

### 1.3 32 任务 / 94 个评分步骤 / 3200 分；终局是 32/32 的闸门

复核 T27 `stack_bowls_three` 与 T10 `plug_charger` 的 `info.json` [S4]，第 7 轮的全量统计保持：

- 32 任务、**94 个评分步骤**、合计 **3200 分**；
- **终局步骤合计 1275 分（39.8%）**；
- **32/32 任务的终局步骤都是该任务的最高权重步骤**；
- 18 个任务所有步骤等权；25 个任务终局权重 ≥40；
- 步骤数分布：11 个任务 2 步、14 个 3 步、5 个 4 步、2 个 5 步；
- 难度 12 Easy / 12 Medium / 8 Hard。

T27 的 30/30/40 与 T10 的 30/30/40 都已逐字复核。**终局步是 success 的 AND 闸门，中间步是 step score 的 SUM 部分分；两者错位，必须字典序处理。**

### 1.4 数据：33,276 条、32 任务、2026-10-14 全量；有校准立体，但没有 depth

- HF collection `unibot-v1-challenge-dataset` 当前 32 个数据集，合计 **33,276** 条 episode（官方挑战页写 32,000 / 169h，HF 扩容后略高）[S3]。
- HangCup 实测 **1,043 条 / 194,564 帧 / 30fps**；所有 32 个数据集的 `lastModified` 均为 **2026-10-14** [S5]。
- 四路相机 `head_stereo_left/right` + `wrist_left/right`，480×640；状态含双臂 7+7 关节、EE pose（base/torso 两套）、夹爪、lower_body；**没有 depth 图像**。
- 高位是校准过的立体对：HangCup 的 `camera_params.head_stereo` 给出 `rectified=true`、基线约 **58.25mm**、焦距约 **282px** [S5]。这是本报告最重要的“使能事实”：**没有 depth，但有可以做度量点云的立体对。**
- 每条任务在 `meta/tasks.parquet` 里有 5 条英文复述；每个任务页还给出 5 个示例 episode [S4]。

立体深度的量级必须算清楚：

```text
Z = f·b / d,   ∂Z/∂d = −Z²/(f·b)

b = 58.25mm, f = 282px
0.5m: d≈32.9px, 1px≈15.2mm, 0.25px≈3.8mm
0.7m: d≈23.5px, 1px≈29.8mm, 0.25px≈7.4mm
1.0m: d≈16.4px, 1px≈60.8mm, 0.25px≈15.2mm
```

结论：**0.5–0.7m 的桌面立体点云足够做“对象/容器级”的 6D 粗配准与变化检测，不够做毫米级插入；毫米级交给腕部视觉伺服 + 柔顺控制。** 这决定了 TIGR 的分桶策略，而不是假装点云能包打一切。

### 1.5 人类干扰备注是公开的逐任务剧本，多数是 1-DOF 平移或撤销

每个任务的 `info.json` 的 `generalization` 字段直接给出 `human_1_note`、`human_4_note`、`unseen_object_3` [S4]。代表性例子：

| 任务 | 官方备注（节选） | 结构 |
|---|---|---|
| T10 PlugCharger | human_4「将插头拔起」 | 撤销插入 |
| T14 PourOutMedicine | human_1「拧开盖子之后拧动回来」 | 撤销开盖 |
| T17 OrganizeStationery | human_4「笔盒合上之后手动打开」 | 撤销闭合 |
| T19 ZipUp | human_4「拉上拉链之后拉开」 | 撤销拉链 |
| T24 ConveyorSorting | human_1/4「可乐/薯片快到了然后放回传送带起点」 | 移动中的目标 |
| T27 StackBowls | human_4「叠了第二个之后拿下第二个」 | 撤销堆叠 |
| T12 Unlock | human_4「中途把锁拿走」 | 移除对象 |
| T08 OrganizeBookshelf | human_1「抓到书后挪动架子」 | 移动容器 |

编号含义（轴编号还是试次编号）官方未解释，**不能断言这就是评测脚本**；但内容本身是高质量的场景先验：绝大多数是“对某个对象做一次 1-DOF 平移”或“在某步完成后撤销它”。这正好是“配准残差 → 变化检测 → 意图回滚”的测试台。

### 1.6 提交接口 v2 未变；没有 depth/外参；N 端口；单模型

`unibot_submission` README 仍是 **2026-08-21** 的 v2（仓库只有 2 次提交）[S6][S7]：

- 观测：4×RGB 480×640、双臂 joint/EE、夹爪、lower_body、单字符串 `observation.language`；
- `metadata` 控制 `control_space`（joint/ee 互斥）、`obs_delta_indices`（选键 + 堆叠）、`image_resize`、`action_chunk_size`、`token`；
- 评测跨 **N 台机器人**，从 8765 起暴露 **N 个连续端口**；每端口独立、状态隔离；
- **API 不暴露相机内参/外参，也没有 depth**；相机固定安装，标定只能靠数据集参数 + 现场自校准。

这意味着：点云配准必须建立在“高位立体对 + 固定外参假设”上，并且所有几何计算都在我们自己的推理侧完成；接口允许我们裁剪/缩放/堆叠图像，也允许在 `get_action` 里做确定性几何运算。

## 2. 问题形式化：短时意图别名与可验证任务态

### 2.1 任务态 POMDP

把一次 episode 写成部分可观测决策过程：

```text
状态   s_t = (T, R, G, k, D, X_t)
  T : 32 个任务之一
  R : 指代对象/部件（抓哪个、哪个槽位、哪个容器）
  G : 目标关系/目标位姿（放到哪、插到哪、叠到哪）
  k : 当前评分步骤（0…K_T−1）
  D : 干扰/变化状态（无、平移、撤销、移除、遮挡）
  X_t : 对象/容器的 6D 位姿与可见性

观测   o_t = (4×RGB, proprio, language)
动作   a_t = (双臂 joint/EE, 夹爪)
```

语言只给 `T` 和部分 `R/G` 的先验；`k`、`D`、`X_t` 必须从历史和几何推断。端到端 VLA 把 `(R,G,k,D)` 压进隐 token，导致同一观测在相邻重规划步之间重采样不同意图——这就是 **intent aliasing**。

### 2.2 为什么“意图识别”不是聊天意图

| 层级 | 内容 | 主要证据 | 现有 VLA 的问题 |
|---|---|---|---|
| 任务意图 | 32 个任务中的哪一个 | 语言（32×5 复述） | 通常能对，但不是瓶颈 |
| 指代意图 | 抓哪个物体/放哪个容器/哪个槽位 | 语言 + 几何 | 位置/背景/未见物品一变就错 |
| 相位意图 | 当前在第几步、上一步是否真完成 | 历史 + 谓词 | 跳步、假完成、重复做 |
| 干扰意图 | 人刚移动了什么/撤销了哪步 | 变化检测 | 继续按旧计划执行 |

**缺口：意图被纠缠在隐式 token 里，没有一个可查询、可验证、可回滚的后验。** TIGR 把意图做成离散变量，用几何证据去推断它，而不是让 VLM 自由生成一段计划。

### 2.3 配准作为观测似然

对每个候选意图 `i = (R,G,k,D)`，用模板配准得到：

```text
T_B^G(i)          # 目标 6D 位姿（base 系）
f_i ∈ [0,1]       # fitness / inlier ratio
r_i               # 残差（inlier RMSE 或点-to-plane 残差）
c_i               # 碰撞/可达/可见性惩罚
```

定义观测似然：

```text
log p(o_t | i) = β1·f_i − β2·r_i/σ_geo − β3·c_i + β4·1[phase consistent]
p(o_t | i) = softmax_i( log p(o_t | i) )
```

配准同时给出四样东西：

1. **6D 目标位姿** → 给动作专家/伺服；
2. **fitness / inlier ratio** → 意图后验的观测似然；
3. **残差场 r(x)** → 步骤完成/放置稳定/变化检测；
4. **对称性下的多假设** → 杯子/碗/盘子的旋转歧义。

这四样正好对应 UniBot 的四个失败面：指代、相位、终局精度、干扰恢复。

### 2.4 排行榜目标与统计功效

```text
主目标 = 32 任务 × 10 次 = 320 trials 的总平均成功率
次目标 = 总平均步骤分（只在成功率打平时使用）
再次 = 提交日期更早
```

统计后果：

- 320 trials，p≈0.30 时总体 SE≈**2.56pp**；+3pp≈1.2 SE，+5pp≈1.95 SE；
- 每任务 10 次，单任务成功率是 **10% 量化**；总榜是 **0.3125pp 量化**；
- **+1 个任务全成功 = +3.125pp 总榜**；+2 个任务 = +6.25pp。也就是说，“+3pp”只是多成功一个任务，不能当胜利；“+5pp”约 1.6 个任务，仍然偏噪声；**目标应是 +2 个任务（6.25pp）或一类任务的系统性修复**。
- 步骤分只在 success 打平时决定名次；但 320 trials 下 1–3 个任务的差异本来就在噪声内，所以**步骤分 tie-break 实际会经常发生**。正确策略是：成功优先；在不降低成功概率的前提下，尽量拿步骤分；当成功已不可能时，切到“salvage 模式”最大化剩余步骤分。

## 3. 失败模型与设计原则

### 3.1 六类断点

| # | 失败模式 | 表现 | TIGR 对策 |
|---|---|---|---|
| F1 | 指代 grounding 错 | 选错物体/容器/槽位；位置/背景/未见物品轴崩 | 意图晶格 + 目标模板配准 |
| F2 | 相位/意图别名 | 同一观测重采样不同 chunk；跳步、重复、假完成 | 历史意图后验 + 步骤图 + 配准验证 |
| F3 | 干扰未检测 | 人移动物体/撤销步骤后仍按旧计划执行 | 场景变化检测 + 意图回滚 |
| F4 | 终局精度不够 | 插入/堆叠/拉链最后 3cm 失败 | 目标模板配准 + 腕部伺服 + RVS |
| F5 | 长程记忆/遮挡 | 物体移出视野后找不到；容器被挡 | 目标模板 + 参考点云 + 容器系表达 |
| F6 | 评测错配 | 追步骤分、被 2–3pp 噪声误导 | 排行榜守卫 + 成功率先行 + salvage |

F1/F2/F3/F5 都是“任务态/意图”问题，不是“动作生成”问题；F4 是系统精度问题；F6 是目标函数问题。TIGR 主要打前四个，保留 PGL/腕部伺服打 F4，LGV 打 F6。

### 3.2 六条设计原则

1. **意图是查询，不是隐变量。** 每个候选意图必须能被显式枚举/打分/回滚；否则无法验证，也无法在干扰后恢复。
2. **配准是证据，不是地图。** 不做稠密 SLAM/3DGS/NeRF；只做任务相关对象/容器与目标模板的局部 6D 对齐。
3. **模板来自演示，不来自 CAD。** UniBot 没有 CAD；33k 演示里的目标状态就是最真实的模板分布。
4. **几何只做它擅长的。** 对象级粗配准、变化检测、终局稳定验证；毫米级插入交给腕部伺服 + 力/电流 + 柔顺。
5. **单模型合规。** 确定性几何/滤波可以放在推理侧；所有学习组件必须在唯一 checkpoint 内；不引入 SAM/RAFT-Stereo 等第二个模型。
6. **排行榜是目标函数。** 任何模块的收益必须能映射到“整任务成功率”；步骤分只在成功不降的前提下优化；2–3pp 不当胜利。

## 4. TIGR-GPR 架构

### 4.1 总览

```text
语言（32×5 复述）
   │
   ▼
IL 意图晶格：任务 × 指代 × 容器/槽位 × 相位 × 干扰
   │
4×RGB + proprio
   │
   ├─ 高位立体 → 任务相关点云（去桌面/自遮挡/聚类）
   ├─ IGL：演示目标模板库（容器系）
   └─ 参考点云（episode 起始/上一步对齐后）
             │
             ▼
IGR 意图引导配准：top-k 模板 → 6D 目标位姿 + fitness + 残差
SCD 场景变化检测：参考配准残差 → 平移/撤销/遮挡/移除
             │
             ▼
IBF 意图信念滤波：p(k, G, D | obs, language)
             │  intent token + goal pose + uncertainty
             ▼
GPR-VLA（单一 checkpoint）：目标 z* − 部件信念 b → 残差 r → Action Expert → chunk
             │
             ▼
RVS 配准验证收尾：缓放 → 残差 < τ_task → 稳定窗口 → nudge/regrasp/retry
             │
             └─► 变化/撤销 → 回滚相位 → 复用 IGL/IGR
```

一句话：**把意图当作查询、把点云配准当作证据、把排行榜当作目标函数；用演示目标模板替代 CAD/2D 锚点，用配准残差同时做意图后验、终局验证和干扰检测。**

### 4.2 IL：意图晶格（Intent Lattice）

IL 不是“更大的任务图”，而是一个**可因子化、可查询、可回滚**的离散结构：

```text
L = { (T, R, G, k, D) }
T ∈ 32 tasks
R ∈ {object_1…object_n, part_1…part_m, none}
G ∈ {slot/region/pose hypothesis} × symmetry orbit
k ∈ {0…K_T−1} ∪ {done, failed}
D ∈ {none, translate, undo, remove, occlude}
```

- **任务层**：32 个任务 × 5 条英文复述；精确串匹配 + 规范化 + 嵌入兜底。
- **指代层**：对象/部件/容器/槽位；由语言先验 + 几何聚类 + 模板配准共同打分。
- **目标层**：容器系下的相对位姿 + 对称轨道（yaw 多假设）；不是单一世界坐标。
- **相位层**：官方 `score_steps` 的线性/偏序图；`k` 只能沿图前进或在干扰下回退。
- **干扰层**：SCD 输出的变化类型；`D` 不是“噪声”，而是意图晶格的一部分。

**意图 token**：

```text
e_int = MLP( onehot(T) ⊕ onehot(R) ⊕ onehot(G_bin) ⊕ onehot(k) ⊕ onehot(D) )
```

训练时用演示的 oracle 标签（任务/步骤/目标）监督；推理时用 IBF 后验的软 token（期望嵌入），避免硬分类错误传播。`e_int` 注入 GPR-VLA 的 language token 之后、action expert 之前。

**为什么是晶格而不是树**：同一观测可能同时支持“放到左槽”和“放到中槽”（位置轴），也可能同时支持“当前步”和“上一步被撤销”（human 轴）。树会强制单一路径；晶格保留多假设，由 IBF 和配准证据消歧。

### 4.3 IGL：演示目标模板库

#### 4.3.1 模板是什么

对每个任务 `T`、每个评分步骤 `k`、每个目标关系 `G`，从官方演示中抽取**目标时刻**的对象/容器点云：

```text
P_{T,k,G}^{(j)} = crop( backproject( stereo_t^j ), mask_{object/container} )
```

- `t`：该步骤完成/释放时刻（由 TLE 的相位切分 + 夹爪事件 + 谓词标签估计）。
- `crop`：只保留任务相关对象/容器/槽位邻域；去桌面、去机器人自遮挡、去背景。
- 坐标系：容器系 `F_C`（桌面平面法向 + 容器主轴 + 质心）；存 `T_C^P`，不存世界坐标。
- 每个 `(T,k,G)` 存 8–16 个原型（按位置/背景/物体实例聚类），每个 2048–4096 点 + 法向。
- 对称物体存多个 yaw 轨道模板；模板库显式标注对称群。

**规模估计**：94 个评分步骤 × 平均 2–3 个目标关系 × 8–16 原型 × 2048 点 × 24B ≈ **100–200MB**。这是数据资产，不是模型；必须在模型卡披露。

#### 4.3.2 为什么不用 CAD / 2D 锚点

- **CAD 不可得**：UniBot 没有物体 CAD；33k 演示是唯一真实的几何分布。
- **2D 锚点不够**：2D 锚点能告诉“往哪投”，但不能给出 6D 朝向、容器系相对位姿、残差场；终局插入/堆叠需要 6D。
- **演示模板覆盖真实分布**：模板来自同一机器人、同一相机、同一桌面高度；比合成 CAD 更少 sim-to-real gap。
- **模板是“目标状态”而不是“动作轨迹”**：迁移的是几何关系，不是轨迹复制；对位置/背景/外观变化更稳健。

#### 4.3.3 模板构建的校准链

1. **立体标定**：用 `camera_params.head_stereo` 的 `K/D/R/T`；检查 `rectified=true`；用桌面平面重投影误差 <5px 做现场复核。
2. **外参**：数据集给 EE base/torso 位姿；用固定安装假设 + 桌面平面 + 已知 EE 轨迹做手眼/外参自校准；现场用标定板/桌面法向复核。若外参误差 >1cm，IGR 降级为 2D 锚点。
3. **容器系**：RANSAC 桌面平面 → 容器点云 PCA/最小外接盒 → 主轴消歧（用语言/演示先验）→ `F_C`。
4. **目标时刻**：夹爪释放事件 + 物体速度/位姿稳定 + 步骤谓词；三选二投票，人工抽检 10%。
5. **抽检**：每任务 10% 模板重投影误差 <1cm、朝向 <5° 才入库；否则重标或丢弃。

### 4.4 IGR：意图引导配准

#### 4.4.1 在线管线

```python
def igr(obs, intent_candidates, templates):
    left, right = rectify(obs.head_stereo_left, obs.head_stereo_right)
    disp = sgbm(left, right)                      # 确定性
    P = backproject(disp, K, baseline)            # 度量点云
    P = remove_table(P)                           # RANSAC 平面
    P = remove_robot(P, proprio, T_base_cam)      # 运动学自遮挡 mask
    clusters = euclidean_cluster(P)               # 对象/容器候选
    hyps = []
    for i in intent_candidates:
        for Tmpl in templates[i]:
            for sym in symmetry_orbit(Tmpl):
                T0 = fpfh_ransac(clusters, sym)   # 粗配准
                T1, fitness, rmse = icp_point_to_plane(clusters, sym, T0)
                hyps.append((i, T1, fitness, rmse, sym))
    return topk(hyps, score)                      # 多假设，不硬选
```

- **SGBM**：480×640、视差范围按 0.3–1.2m 设定；左右一致性检查 + 中值滤波 + 小连通域去除。
- **去桌面**：RANSAC 平面；桌面法向用于容器系和重力对齐。
- **去机器人**：用 proprio + 固定外参把机器人连杆投影到点云，剔除自遮挡；不依赖第二个分割模型。
- **对象聚类**：欧氏聚类 + 颜色/法向一致性；透明/反光物体失败时回退 2D 锚点。
- **粗配准**：FPFH + RANSAC；模板与场景下采样到 5–10mm。
- **精配准**：point-to-plane ICP；fitness = inlier ratio；rmse = inlier RMSE。
- **对称**：对杯子/碗/盘子/盒子生成 yaw 轨道；保留 top-k，不强行选一个。
- **评分**：

```text
S(i, T) = w1·fitness − w2·rmse/σ_geo − w3·prior(i) − w4·collision(T) − w5·occlusion(i)
```

`prior(i)` 来自 IL/IBF；`collision` 用夹爪/物体包围盒与容器/桌面做确定性检查；`occlusion` 用可见点比例。

#### 4.4.2 分桶策略

| 桶 | 任务类型 | 几何用法 | 终局精度来源 |
|---|---|---|---|
| A | 刚性放置/堆叠/排列（T01/T02/T04/T06/T08/T13/T15/T20/T21/T25/T27 等） | 容器系 6D 配准 + 模板残差 | IGR 粗位姿 + 腕部伺服 |
| B | 插入/插拔/翻转（T05/T10/T11/T12/T26/T30/T32 等） | 端口/夹具局部配准 + 轴向 | 腕部视觉伺服 + 力/电流 + 柔顺 |
| C | 铰接/形变/拉链/布料（T07/T09/T14/T16/T17/T18/T19/T23/T28/T29/T31 等） | 只配准刚性容器/把手/锚点；不建布料物理 | 2D 锚点 + 相位先验 + 力控 |
| D | 移动目标（T24） | 参考点云 + 帧间变化 + 预测 | 跟踪 + 重新抓取 |

**明确不做**：用点云做毫米级插入；用点云建布料/拉链/透明物体的完整物理；用稠密 SLAM/3DGS/NeRF 建整桌地图。这些在第 7 轮已被修剪，本轮继续不做。

#### 4.4.3 残差场

配准后，对每个场景点 `x` 计算到模板最近点的距离 `r(x)`；按对象/区域聚合：

```text
R_obj = quantile_90( r(x), x ∈ object )
R_region = quantile_90( r(x), x ∈ goal_region )
```

- `R_obj` 小、`R_region` 小 → 对象已在目标位姿（步骤可能完成）。
- `R_obj` 大、`R_region` 小 → 对象未到位（继续放置）。
- `R_obj` 小、`R_region` 大 → 容器/目标被移动（干扰）。
- 两者都大 → 对象/容器被移动或遮挡（变化检测）。

### 4.5 SCD：场景变化检测

SCD 不是“帧差”，而是**配准残差的结构化解释**：

```text
输入：当前点云 P_t、参考点云 P_ref、当前意图 i、模板 T_i
输出：变化事件 {none, translate(obj, Δ), undo(step), remove(obj), occlude(obj)}
```

步骤：

1. 把 `P_ref` 与 `P_t` 用当前意图的容器系对齐（或直接用 IGR 的 `T_B^C`）。
2. 计算残差场 `r(x)`；对残差做欧氏聚类，得到变化簇。
3. 对每个簇：
   - 若簇的质心位移 > `τ_move` 且形状不变 → `translate`；
   - 若簇对应某个已完成步骤的对象/关系消失 → `undo`；
   - 若簇对应对象整体消失 → `remove`；
   - 若簇在机器人/人臂运动轨迹上且短暂 → `occlude`（不触发回滚）。
4. 用机器人运动学 mask 剔除自遮挡；人臂不建模型，只当“遮挡/干扰”，避免误判为对象移动。
5. 时间迟滞：连续 2–3 帧同向证据才触发；单帧大残差只报警不动作。

**为什么用参考点云而不是只靠模板**：模板是“目标状态”，参考点云是“本 episode 起始状态”。两者的残差分别回答“离目标多远”和“相对起始变了什么”；干扰检测需要后者。

### 4.6 IBF：意图信念滤波

在 IL 上做离散贝叶斯滤波：

```text
b_t(i) ∝ p(o_t | i) · Σ_j A_{ij} · b_{t−1}(j)
```

- `A`：意图转移矩阵。相位 `k` 只允许沿任务图前进/回退；`D` 的转移由 SCD 事件驱动；`R/G` 在任务内相对稳定，只允许小范围切换。
- `p(o_t | i)`：IGR 的配准似然（§2.3）+ 语言先验 + 碰撞/可达惩罚。
- **迟滞**：相位前进需要连续 2 次后验 >0.7 或一次强谓词；回退需要 SCD 强证据。防止在相邻 chunk 间抖动。
- **软 token**：`e_int = Σ_i b_t(i) · e_i`；低置信度时把 `e_int` 的方差作为 uncertainty token 注入 GPR-VLA，让策略知道“现在该保守/该验证”。
- **计算**：IL 的候选数在单任务内可控（指代 ≤10、目标 ≤8、相位 ≤5、干扰 ≤5），矩阵乘法 <1ms；不需要第二个模型。

**与 IntentVLA 的关系**：IntentVLA 用近期视觉历史编码短时意图，解决 chunk 间的意图冲突；TIGR 进一步把意图做成**可解释的离散后验**，并用几何配准提供观测似然。两者不冲突：IntentVLA 的历史编码可以作为 IBF 的额外观测项，但 TIGR 不依赖它。

### 4.7 RVS：配准验证收尾

RVS 把“释放”当成需要验证与修复的阶段，而不是“放完就完”：

```python
def rvs(step, obs, plan, budget=2):
    for attempt in range(budget + 1):
        for chunk in stream(policy.act(obs, plan, s=step)):
            send(chunk)                                  # 30Hz
            if predicate_met(step, obs):
                break
        open_gripper(slow=True)
        sleep(0.5)                                       # 静置窗口
        fit, rmse, residual = igr_verify(obs, step)      # 配准验证
        if fit > τ_fit and rmse < τ_task and stable(obs, window=0.5):
            return True
        if repairable(residual):
            plan = nudge_plan(step, obs)                 # 推正/轻压
        else:
            plan = regrasp_plan(step, obs)               # 重抓
    return False
```

- `τ_task`：同任务演示间目标位姿的 95 分位差；叠碗大、插头小。
- `stable`：对象相对位姿在 0.5s 内位移 < `ε_rel` 且谓词保持。
- `predicate_met`：IL 的步骤谓词 + 配准残差双证据；单靠语言/分类头不够。
- **预算**：普通任务 ≤2 次；长程任务（T16/T17/T31）≤1 次；Endurance Governor 兜底 180s。
- **salvage**：当 RVS 判断成功已不可能，切到“最大化剩余步骤分”模式，但绝不为了步骤分冒成功风险。

### 4.8 LGV：排行榜守卫

LGV 不是“看榜”，而是**实验设计与选模规则**：

```text
1. 任何改动先问：它提高的是 success 还是 step_score？
   - success 优先；step_score 只在不降低 success 的前提下优化。
2. 用配对 bootstrap 估计 Δsuccess 的置信区间；报告 P(Δ>0)、rank interval。
3. 用 rank probability 而不是均值选 checkpoint：
   P(rank ≤ r) = bootstrap 频率；避免被 2–3pp 噪声骗。
4. 目标：+2 个任务（6.25pp）或一类任务系统性修复；
   不把 +1 个任务（3.125pp，约 1.2 SE）当胜利。
5. 提交时机：早提交有 tie-break 期权，但不为噪声提前交；
   具体提交次数/保留规则未核实，标开放问题。
6. salvage：成功无望时最大化剩余步骤分；成功有望时绝不降成功率换步骤分。
```

**N-SCORE/rank interval 的用途**：在本地/调试槽样本很少时，用归一化分数和 rank 区间表达不确定性；不把点估计当真实排名。具体统计方法见 [S19][S20][S21]。

### 4.9 GPR-VLA 接口与损失

保留第 7 轮的 GPR-VLA：语言 → 目标 `z*`，部件信念 `b`，残差 `r = z* − b`，flow-matching action expert 出 chunk。TIGR 增加：

```text
输入：language token + e_int + goal pose T_B^G + uncertainty + RIR context
输出：action chunk + 预测的 phase/goal 辅助头（仅训练用）
```

损失：

```text
L = L_flow
  + λ1 L_goal        # 预测目标位姿/容器系相对位姿（训练时 oracle）
  + λ2 L_phase       # 步骤分类/谓词 BCE
  + λ3 L_intent      # 意图晶格因子分类（辅助）
  + λ4 L_change      # SCD 事件分类（训练时合成/备注回放）
  + λ5 L_reg         # 配准质量/残差预测（可选蒸馏）
  + λ6 L_ctx         # RIR 上下文一致性
```

起始权重建议：`λ1=0.1, λ2=0.2, λ3=0.05, λ4=0.05, λ5=0.05, λ6=0.05`；`L_flow` 为主。训练时必须注入 IGL/IGR 的**同分布输出**（含噪声/失败案例），否则推理期首次见到几何特征会崩。

### 5.1 数据使用

| 步 | 操作 | 产出 | 验收 |
|---:|---|---|---|
| 1 | 立体标定复核 | `K, b, R, T` | 桌面重投影 <5px |

| 3 | 相位切分 | 每 episode 的 `t_k` | 夹爪/速度/谓词三选二 |

### 5.3 标签与恢复数据

- **相位标签**：TLE 的步骤切分 + 夹爪事件 + 物体稳定；人工抽检 10%。
- **指代/目标标签**：从演示的 EE 轨迹 + 对象 track + 容器系自动生成；语言复述提供弱标签。
- **恢复数据**：
  - 官方 human 备注 → 1-DOF 平移/撤销剧本；
  - 对演示做反事实编辑（移动对象/容器/目标、撤销步骤）；
  - 用 ACP/GF 控制合成比例，合成不主导（<30%）。
- **负样本**：配准失败、遮挡、透明、对称歧义、错误指代；这些负样本对 IBF/SCD 的校准比正样本更重要。

### 5.4 计算与存储

- 模板库 100–200MB；RIR 缓存 <1GB；无需保存全部点云。
- 离线建库：8×H100 约 4–6 天（含抽检）；CPU 集群可并行。
- 在线几何：SGBM + 聚类 + FPFH/RANSAC/ICP 目标 <30ms/帧（CPU，480×640，下采样）；p99 <100ms。若超标，降点云分辨率/候选数/模板数。

## 7. 部署、延迟与单模型合规

### 7.1 部署形态

```text
每端口一个 episode 状态：
  - IL 当前后验 b_t
  - 参考点云 P_ref（episode 起始）
  - 当前容器系 T_B^C
  - 已用模板缓存 / RIR 缓存句柄
  - 重试预算 / 时间守卫
```

- `reset()` 清空 episode 状态；模板库/RIR 缓存跨 episode 只读。
- 所有几何计算在本地 CPU/GPU；不调用外部服务；不依赖网络。
- 多端口并发时，模板库只读共享，状态隔离；批量 SGBM/ICP 可按端口分组。

### 7.2 延迟预算

| 模块 | 目标 p50 | 目标 p99 | 备注 |
|---|---:|---:|---|
| 立体校正 + SGBM | 8ms | 20ms | 480×640，下采样 |
| 去桌面/去机器人/聚类 | 5ms | 15ms | RANSAC + 欧氏聚类 |
| FPFH + RANSAC + ICP | 10ms | 40ms | top-k 候选，可并行 |
| IBF/SCD | <1ms | 3ms | 小矩阵 |
| GPR-VLA action chunk | 20–50ms | 100ms | 6B + LoRA/量化 |
| 总 `get_action` | 50ms | 150ms | 目标 <100ms，超时降级 |

**降级策略**：p99 超标 → 减少模板数/候选数 → 跳过 FPFH 用上一帧位姿热启动 → 只用 2D 锚点 + 腕部伺服。绝不因为几何慢而丢控制频率。

### 7.3 单模型合规阶梯

| 级别 | 做法 | 合规性 | 性能 |
|---|---|---|---|
| L0 | 纯 GPR-VLA | 最稳 | 基线 |
| L1 | +确定性 IGL/IGR/IBF/RVS（无学习） | 稳（几何算法） | 最小可运行 |
| L2 | +IL/SCD 小头（同一 checkpoint） | 稳（单模型） | 推荐 |
| L3 | +RIR 缓存编码（独立预编码） | 需披露；若算第二模型则降级 | 高 |
| L4 | +SAM/RAFT-Stereo 等外部模型 | **不做** | — |

**模型卡必须披露**：模板库来源/规模、RIR 缓存是否独立编码、所有学习组件是否在同一 checkpoint、是否使用外部数据/预训练权重、确定性几何算法的版本与参数。

## 9. 创新点清单（持续迭代；动机/差异/可行性/资源/步骤/风险/状态）

> 状态说明：押注=本轮主线；保留=沿用；升级=旧点被改造；降级=保留但不再是主回路；砍=不做。

### I1 IL 意图晶格（新增，押注）

- **动机**：IntentVLA 证明短时意图/相位/上下文会造成 chunk 间冲突；UniBot 的 human 轴又直接撤销步骤。需要显式、可回滚的意图变量。
- **差异**：不是任务树/状态机，而是因子化晶格 `(T,R,G,k,D)`；保留多假设，由 IBF 消歧；可查询、可验证、可回滚。
- **可行性**：32 任务 × 5 复述可精确匹配；官方 score_steps 给出相位骨架；指代/目标由几何模板打分。
- **资源**：无额外数据；CPU；1 人周。
- **步骤**：解析 score_steps/复述 → 建晶格 → 接 IBF → 接 GPR token。
- **风险**：候选爆炸 → 任务内剪枝；语言未覆盖 → 嵌入兜底；相位噪声 → 迟滞。
- **状态**：押注。

### I2 IGL 演示目标模板库（新增，押注）

- **动机**：没有 CAD、没有 depth，但 33k 演示有真实目标状态；模板是最便宜的可验证几何先验。
- **差异**：模板是容器系下的目标点云，不是动作轨迹；多原型 + 对称轨道，不做单一平均。
- **可行性**：立体 + EE 位姿 + 夹爪事件足够建库；存储 100–200MB。
- **资源**：8×H100 4–6 天；抽检 10%。
- **步骤**：标定 → 相位切分 → 目标点云 → 容器系 → 聚类 → 入库。
- **风险**：透明/反光/形变目标模板失效 → 分桶回退；分布漂移 → 现场参考点云。
- **状态**：押注。

### I3 IGR 意图引导配准（新增，押注）

- **动机**：配准同时给 6D 位姿、fitness、残差场、多假设；这是把意图落到几何证据的接口。
- **差异**：用演示模板替代 CAD；用意图先验裁剪候选；用残差同时做后验/验证/变化检测。
- **可行性**：SGBM/FPFH/RANSAC/ICP 都是成熟确定性算法；480×640 可实时。
- **资源**：CPU/GPU 几何；无重训也可用（E1）。
- **步骤**：立体 → 去桌面/自遮挡 → 聚类 → 粗配准 → ICP → 评分。
- **风险**：立体噪声/透明物体 → 分桶；对称歧义 → 多假设；外参误差 → 自校准/降级。
- **状态**：押注。

### I4 SCD 场景变化检测（新增，高优先）

- **动机**：官方 human 备注大多是 1-DOF 平移/撤销；现有 VLA 不会检测“世界变了”。
- **差异**：用配准残差的结构化解释，不是帧差；区分平移/撤销/移除/遮挡；机器人自遮挡 mask。
- **可行性**：参考点云 + 当前点云 + 容器系对齐即可；无需训练。
- **资源**：无额外数据；CPU；3 天。
- **步骤**：参考点云 → 残差聚类 → 事件分类 → 迟滞 → 接 IBF。
- **风险**：人臂误判 → 只当遮挡；透明物体 → 残差噪声；阈值 → 验证集校准。
- **状态**：高优先。

### I5 IBF 意图信念滤波（新增，高优先）

- **动机**：意图别名需要跨时间证据；单帧分类会抖。
- **差异**：在 IL 上做离散贝叶斯滤波；转移矩阵由任务图/SCD 驱动；软 token + uncertainty。
- **可行性**：候选数小；矩阵运算 <1ms；可用演示统计初始化。
- **资源**：无额外数据；CPU；1 人周。
- **步骤**：转移矩阵 → 似然 → 迟滞 → 软 token → 校准。
- **风险**：模型错配 → 温度/阈值校准；历史泄漏 → 只保留 2–3 帧。
- **状态**：高优先。

### I6 RVS 配准验证收尾（升级 SVL，押注）

- **动机**：终局是 32/32 闸门；释放失败靠“放完就完”发现不了。
- **差异**：用配准 fitness/残差 + 谓词稳定双证据；nudge/regrasp/retry；成功无望才 salvage。
- **可行性**：IGR 已给残差；腕部相机 + 力/电流可用；180s 够 1–2 次。
- **资源**：无新增数据；控制循环；1 人周。
- **步骤**：缓放 → 静置 → 验证 → 修复 → 预算守卫。
- **风险**：耗时 → 长程任务限 1 次；误判 → 双阈值；透明 → 回退 2D。
- **状态**：押注。

### I7 LGV 排行榜守卫（新增，高优先）

- **动机**：排名是成功率先行；320 trials 噪声大；占位榜会误导。
- **差异**：把评测当目标函数；配对 bootstrap/rank probability；success-first + salvage。
- **可行性**：纯流程/统计；无需训练。
- **资源**：1 人周；评测脚本。
- **步骤**：指标 → bootstrap → 选模规则 → 提交策略。
- **风险**：提交规则未核实 → 保守；样本少 → 报告区间不报点估计。
- **状态**：高优先。

### I8 GPR-VLA + intent token（升级，保留）

- **动机**：GPR 的目标残差/可逆信念与 TIGR 天然对齐；intent token 把几何后验注入策略。
- **差异**：增加 `e_int`、目标位姿、uncertainty、RIR context；辅助头只在训练用。
- **可行性**：WLA-1.0-Base 可 LoRA；接口不变。
- **资源**：8×H100 2–3 周。
- **步骤**：token 注入 → 辅助损失 → 同分布几何注入 → 蒸馏。
- **风险**：几何特征域差 → 训练注入失败案例；过拟合 → 冻结/降权。
- **状态**：升级/保留。

### I9 RIR 配准不变检索（升级 ICR，中优先）

- **动机**：演示检索能提供少样本上下文；但全局外观键会被背景/位置 OOD 打崩。
- **差异**：键用容器系相对位姿、对象关键点、相位、运动统计；不用全局外观。
- **可行性**：33k 演示可切段；HNSW <5ms；缓存 <1GB。
- **资源**：编码 1–2 天；ANN。
- **步骤**：切段 → 几何键 → 缓存 → 训练注入 → 延迟压测。
- **风险**：透明/形变键失效 → 回退相位先验；延迟 → 降 K/降维。
- **状态**：中优先。

### I10 NRB 官方备注恢复（升级，中优先）

- **动机**：human 备注是公开剧本；直接对应评测干扰。
- **差异**：从“自造扰动”升级为“官方备注回放 + 通用 1-DOF 兜底”；与 SCD/IBF 联动。
- **可行性**：备注多为刚体平移/撤销；合成便宜。
- **资源**：ACP/GF 管线；2–3 天。
- **步骤**：备注表 → 场景脚本 → 破坏/恢复对 → 加权训练。
- **风险**：编号含义未核实 → 同时覆盖通用扰动；合成负迁移 → 真实混采。
- **状态**：中优先。

### I11 TLE/ACP/GF 数据引擎（保留，修剪）

- **动机**：真实锚定的反事实仍是最便宜的轴数据。
- **差异**：本轮只服务相位/指代/目标/恢复；不做全任务孪生。
- **资源**：沿用第 7 轮。
- **风险**：合成主导 → GF 软权重 + <30% 上限。
- **状态**：保留/修剪。

### I12 DebugLoop 平台调试回路（保留）

- **动机**：比自建孪生更可信的真机反馈；发布门控。
- **差异**：制度化使用不计分单任务调试槽；每个大版本 1 槽。
- **风险**：资源稀缺 → 只做假设检验，不做 A/B 显著性。
- **状态**：保留。

### I13 FLEET/Compliance（保留，降级）

- **作用**：N 端口、状态隔离、soak、健康检查、单模型/数据来源审计。
- **状态**：降级为工程检查单，不再作为研究轴。

### 已砍清单（跨轮）

- 稠密 SLAM / 3DGS / NeRF / 全桌重建；
- 相位 MoE / per-task LoRA / 多模型堆叠；
- 全 32 任务高保真孪生 / 自由仿真数据 / 运行时 MPC/RL；
- 布料/拉链/透明物体的完整物理；
- WMA-0 进主路径；大实验室网络作为主路径；
- 步骤分优先目标；为 2–3pp 噪声提前提交。

## 10. 风险、合规与开关

| 风险 | 影响 | 缓解 | 开关 |
|---|---|---|---|
| 立体噪声/透明反光 | 点云缺失/残差大 | 分桶；回退 2D 锚点 + 腕部伺服 + 力/电流 | 任务级 |
| 外参误差 | 配准偏 | 数据集参数 + 桌面平面自校准；误差 >1cm 降级 | 全局 |
| 对称歧义 | 选错 yaw | 对称轨道多假设；IBF 保留 top-k | 对象级 |
| 机器人/人臂遮挡 | 误判对象移动 | 运动学自遮挡 mask；人臂只当遮挡 | 全局 |
| 模板分布漂移 | 目标误差大 | 现场参考点云；每 episode 重估容器系 | 场景级 |
| 单模型合规 | 取消资格 | 确定性几何 + 唯一 checkpoint；不用 SAM/RAFT | 全局 |
| 外部数据/预训练权重 | 规则未核实 | 默认 OFF；邮件确认后 ON | 数据级 |
| 调试槽稀缺 | 无法充分验证 | 每版 1 槽；只做假设检验 | 流程 |
| 统计噪声 | 误判提升 | +2 任务目标；bootstrap/rank interval | 评测 |
| 延迟超标 | 控制掉帧 | 降候选/降分辨率/热启动；p99 守卫 | 运行时 |

**合规底线**：

1. 所有学习组件（GPR-VLA、IL/SCD/IBF 小头、RIR 编码器）必须在**同一个 checkpoint**；若 RIR 编码器独立，必须证明它只是缓存/特征提取且不构成第二模型，否则降级。
2. 确定性算法（SGBM、RANSAC、ICP、IBF 矩阵、SCD 规则）不算“第二个模型”，但要在模型卡披露版本/参数。
3. 模板库是数据资产，不是模型；来源必须是官方数据或明确许可的数据；外部数据默认 OFF。
4. 不用 SAM/RAFT-Stereo/FoundationPose 等第二个模型；若需要语义分割，用几何聚类或蒸馏进唯一 checkpoint。
5. 不在评测中调用外部 API/云服务；所有计算在自部署服务内。
6. 不针对占位榜/测试集过拟合；所有阈值用训练/验证集校准。

## 13. 开放问题

1. 外部数据（自采/实验室/公开数据集/合成数据）是否允许？预训练权重（WLA/WALL-OSS/MolmoAct）是否允许？——邮件已备好。

4. 步骤分聚合公式（episode 部分分平均？取最好？）；成功率 tie-break 的精确规则。
5. 备注编号（human_1/human_4/unseen_object_3）是轴编号还是试次编号？评测是否就在这些剧本里采样？
6. 语言指令是英文 5 复述之一、中文、还是未见复述？IL 解析的兜底强度。
7. N 台评测机器人的数量；每端口并发/延迟上限；30Hz 控制是否严格。
8. 180s 内允许的连续重试/自我中断上限是否有隐藏规则。
9. 评测是否提供桌面高度/相机外参的标定信息？还是必须自估？
10. 真实榜单发布后，重跑“30% 系统假设”，用真实 q/p_t 替换占位先验。
11. 模板库/演示目标点云是否被允许作为“数据资产”随模型提交？大小限制？
12. 透明/反光物体在立体下的失败率；是否需要专门的偏振/结构光（当前接口没有）。
