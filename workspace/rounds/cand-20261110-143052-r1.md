# 第 45 轮（承接第 44 轮 v21；本轮灵感：推理延迟 × 竞品分析） · Temporal-Cert × Competitive-Cert：把「延迟」升为证书的第二根信任，把「竞品分析」升为可认证的竞争比审计（四层架构 v10）

> 承接第 44 轮 v21（Pose-Cert × Data-Cert）。v21 自陈最大风险是「分层条件覆盖依赖审计独立性，否则沿自采流形自我确认」。但它与 v19–v21 整个证书栈共享一个更隐蔽、更致命的未言明假设：**(H4) 一份在观测时刻 τ 成立的证书，在机器人真正执行的动作时刻 t_act 仍然成立**。所有覆盖保证都写在 τ，而决策实际发生在 τ+L_e2e+H_act；中间横跨姿态更新、几何证书、INT8 监控、VLM 仲裁、共形集构造与可能的超时重试。v21 把延迟当作事后检查的 p99 性能指标（<150μs），而不是证书义务。后果是：**一份数学上 sound 的证书，可以因为来晚了、或用的是陈旧观测，而在执行时静默不 sound**。更糟的是，延迟尾部与不确定性尾部**正相关**——透明/镜面/遮挡/快速运动这些「难场景」恰好既推理更慢、姿态更不确定。与此同时，v21 从未回答「我们这套证书栈相对离线 oracle 与真实竞品到底值不值」：一个 sound 但保守 100×、慢 100× 的系统永远不会落地。两个灵感词精确命中 H4：**推理延迟**迫使我们把「时间」升为与「姿态」并列的第二根声音性根，把「来不来得及」写成可校准的证书；**竞品分析**（双重含义：字面竞品/榜单，以及在线算法的 competitive ratio vs 离线 oracle）迫使我们把「比谁好」变成有置信度、信息对等、反樱桃挑选的可审计竞争比。二者耦合出本轮真正的新问题：**证书三难（soundness × latency × competitiveness）——安全要保守与计算，延迟要省计算与紧 margin，竞品要低延迟高可用；而竞品分析的平均值恰恰会把「安全失效所在的尾部」平均掉**。

## 0. 直觉与动机

**灵感 1（推理延迟 → 证书的第二个根是「在死线前、用不陈旧的输入，算出来才算数」）**
直觉：与其问「这份证书对不对」，不如问「它是否在死线前送达，且其不确定性半径已经为『送达前的漂移』买过单」。于是把执行时间也做成**分层共形证书**：对每个阶段/每个输入层，给出高概率执行时间上界 L̂_{1−β}（P(L ≤ L̂_{1−β} | ω_L) ≥ 1−β），端到端用直接校准 L_e2e（而非盲目相加）并报告尾部与 n_eff。时间证书和姿态证书一样，都是「集合 + 条件覆盖」，只是把样本轴从位姿换成执行时间。这样「来不及」不再是静默事故，而是一个被显式度量的违约事件。

**灵感 2（时-不确定交换 → 等待即漂移，延迟按谓词与运动状态定价）**
直觉：姿态租约 r(t) 随时间增长；从观测 τ 到执行 t_act = τ+L_e2e+H_act，有效半径是 r_eff = r(t_act)，而不是 r(τ)。于是延迟直接吃掉不确定性预算，交换率 κ_t = ∂m/∂L = L_φ·r′(t_act) = L_φ(λ_o + λ_d/(2√(t_act−τ)))。**同一毫秒对不同谓词、不同运动状态的价格完全不同**：机器人静止时延迟廉价，快速挥臂时延迟昂贵；碰撞谓词的 L_φ 大于边距谓词。这把「调度」从工程调参变成一个有可证明优先级的资源分配问题：按 κ_j × 边际 margin/μs 排序。

**灵感 3（竞品分析 → 双重含义：离线 oracle 的竞争比 + 真实竞品的公平基准）**
直觉：只说「我们 sound」没有意义，必须回答「相对谁、在什么信息条件下、差距由什么构成」。第一层是**算法意义**：定义逐实例竞争比 ρ = sup_I cost(π)/cost(π*)，π* 是拥有完整未来信息的离线 oracle；并在封存分布上给出有限样本的置信上界 ρ_{1−δ}。第二层是**产品意义**：与真实竞品做**信息对等**（同传感器、同算力、同执行器、同时序）与**测量对等**的配对比较，报告安全调整后的 Pareto 前沿，而不是单一分数。关键新指标是**认证价格 PoC = cost(π_cert) − cost(π_comp)**，并把它分解为「安全成本 / 延迟成本 / 保守成本」——这既是研究结论，也是产品叙事。

**灵感 4（耦合 → 双根声音性 + 证书三难 + 尾部相关性）**
直觉：v9 只有一个根（姿态=真值），v10 有两个根（真值 + 时间）。一份动作要算数，必须同时满足「姿态盒覆盖真值」与「时间证书覆盖送达」。最危险的错误是把两个独立校准的 1−α、1−β 直接相乘冒充联合覆盖：难场景下 (慢,不确定) 正相关，联合覆盖会**低于**乘积，尾部被系统性高估。因此必须做**联合共形**（对 (位姿残差, 延迟残差) 的联合分数校准），并显式检测相关性漂移。竞品分析若只报均值/均值±1σ，就会把这条尾部平均掉——于是「平均更优、尾部不 sound」成为最难发现、也最危险的失败模式。

**耦合升级**：TCE（时序证书引擎）为每个证书附加时间戳、死线租约与端到端执行时间证书，并计算时-不确定交换率；TCS（时序证书调度器）在死线约束下按交换率分配随时精化预算；CCA-II（竞品与基准审计器）用封存预注册基准给出认证竞争比、信息对等审计与反樱桃挑选。四层架构 v9 升级为 v10：在「姿态根信任 + 校准数据治理」之上再加**时间根信任（与姿态并列）**与**竞品/基准审计层**，形成「真值 × 时间 × 数据 × 覆盖 × 竞品」的可审计闭环。

## 1. 形式化定义（增量：定义 50–56）

**定义 50（分层的执行时间共形证书）**
对每个证书生成阶段 i∈{姿态, 几何, CAR 查表, INT8 监控, 仲裁, 共形集, 规划} 与输入层 ω_L（与姿态可观测性层 ω 合并或细化），观测执行时间样本 {L_i}。给出**条件时序证书**：
P(L_i ≤ L̂_{i,1−β_i} | ω_L) ≥ 1−β_i。
端到端 L_e2e = Σ_i L_i + 交接/序列化开销 + 重试惩罚。组合时**优先直接对 L_e2e 的联合样本做分块共形**（能吸收阶段间相关与负载耦合），阶段相加只作保守上界；报告尾部（p99/p999）、n_eff、ε_shift（与定义 47 同源）。**禁止只报均值或 p50 冒充时序证据**。

**定义 51（时-不确定性交换与时间有效证书）**
沿用姿态租约 r(t)。设观测时刻 τ、动作时刻 t_act = τ + L_e2e + H_act（H_act 为执行/通信时延）。**有效半径**
r_eff = r(t_act) = r_ω + λ_o·(L_e2e+H_act) + λ_d·√(L_e2e+H_act)。
证书 c 在 t_act **时间有效**当且仅当：(i) 死线满足 L_e2e ≤ L_max(φ,θ)；(ii) 新鲜度满足 r_eff ≤ r_max(θ,φ)。**交换率** κ_t(φ) = ∂m/∂L = L_φ·r′(t_act) = L_φ·(λ_o + λ_d/(2√(t_act−τ)))。可靠性命题：若仅用 r(τ) 扣 margin 而实际执行于 t_act>τ，则 margin 被系统性高估 L_φ·(r(t_act)−r(τ))，且该高估随运动速度与延迟增长——这是 v21 的隐藏漏扣。

**定义 52（双根联合证书与尾部相关性）**
**不得假设**姿态误差与执行时间独立。定义联合分数 s = max(e_pose / r_max, L_e2e / L_max)（或更一般的 copula 构造），按层对联合样本 (e_pose, L_e2e) 做共形，得到**联合证书**：
P(e_pose ≤ r_max ∧ L_e2e ≤ L_max | ω) ≥ 1−γ。
**双根 soundness 定理**：若联合证书成立、且安全谓词在姿态盒 P_t 上做 □ 提升成立，则动作时刻 φ 成立的概率 ≥ 1−γ（γ 已同时覆盖时间与姿态残差）。**反例警告**：若分别用 1−α_p 与 1−β 的独立界相乘，则在 corr(e_pose L_e2e)>0 的难场景层会**高估**联合覆盖（因为二者一起变差），必须用联合校准或给出显式相关性上界 ρ_corr 并做保守修正。

**定义 53（随时证书与单调精化）**
证书族 {c_γ : γ∈Γ}（γ 为计算预算）。要求：(i) **任意中断点都 sound**（imprecise computation 的可用性）；(ii) rad(c_γ) 关于 γ **单调不增**；(iii) 精化曲线给出边际收益 ∂rad/∂γ。运行中可随时降级到更粗但依然 sound 的证书，从而把「来不及」从**安全失败**降为**精度/可用性下降**。这要求每个精化步骤都维持一个可验证的不变量：当前返回的界始终是真实误差的上界。

**定义 54（死线约束下的证书调度）**
给定证书任务集 {c_j}、每任务可选预算 γ_j、交换率 κ_j、关键级与死线 L_max(j)。在周期与各死线约束下最大化期望认证 margin（等价最小化期望风险），即**带随时精化的在线随机背包/调度**：
max E[Σ_j U_j(γ_j)]  s.t.  L_e2e(j) ≤ L_max(j),  Σ_j time_j(γ_j) ≤ T_period。
贪心策略按 κ_j·(边际 margin/μs) 排序并允许抢占 anytime，可给 1/2 类竞争比保证。**安全凌驾**：任何时刻若某关键级 j 的死线+新鲜度双闸门不满足，则对该 j 直接降级或 fail-closed，绝不为「腾预算给别人」而牺牲高关键级证书。

**定义 55（认证竞争比：对手是离线 oracle 与真实竞品）**
定义代价向量 cost = (安全违例, 可用性损失, 延迟, 保守度)。对策略 π：**逐实例竞争比** ρ(π) = sup_I cost(π;I)/cost(π*;I)，π* 拥有完整未来信息；**分布认证竞争比**在封存基准分布 D 上用有限样本给置信上界 ρ_{1−δ}。对真实竞品 π_comp，在**信息对等**（同传感器、同算力、同执行器、同时序信息）与**测量对等**（同场景、同指标、同运行预算）下做配对比较，报告安全调整后的 **Pareto 前沿**而非单一分数。**认证价格** PoC = cost(π_cert) − cost(π_comp)，分解为「安全成本 / 延迟成本 / 保守成本」。若竞品拥有 UniBot 没有的传感器（深度/力/触觉），必须把它记为信息不平等的上界，不得直接宣称更优。

**定义 56（基准独立性与反樱桃挑选）**
基准集 B 必须 ⟂ 开发过程：预注册指标与分层、封存、版本哈希、隐藏场景族。防多重比较/选择性报告：预注册主指标 + Holm/Bonferroni 校正；报告**全部**运行而非最好一次。**基准 Goodhart**：若策略针对 B 反复调参，则 B 上的竞争比不再外推；用隐藏层与 held-out 场景族检测。检测统计量与定义 49 的选择偏差界同构——把「覆盖 Goodhart」推广为「基准 Goodhart」。**闭环降级**：若时序证书失败、联合覆盖失败、或基准环境漂移超界，则关闭认证扩张、退回「保守先验姿态盒 + 更短租约 + 纯查表/安全停机」。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-63 TEMPORAL-CERT-ENGINE（时序证书引擎 TCE）
1. **分层时序共形**：按阶段与输入层校准执行时间上界 L̂，端到端直接校准并报告尾部/n_eff/ε_shift，禁止只报均值。
2. **时-不确定交换**：由 L_e2e、H_act 计算 r_eff 与交换率 κ_t；输出「时间有效」判定（死线 + 新鲜度双闸门）。
3. **双根联合证书**：联合分数 s 的按层共形，输出联合覆盖界；检测 (e_pose, L) 相关性漂移并触发保守修正。
4. **随时精化 API**：任意中断返回 sound 证书、保证单调性，暴露精化曲线供调度器使用。

### 2.2 IP-64 COMPETITIVE-CERT-AUDITOR（竞品与基准审计器 CCA-II / BCA）
1. **封存预注册基准**：指标/分层/场景族预注册、版本哈希、隐藏层；开发期不可读评估集。
2. **认证竞争比**：对离线 oracle 的逐实例与分布竞争比（含置信上界）；对真实竞品的配对比较。
3. **信息/测量对等审计**：核对传感器、算力、执行器、时序信息与运行预算；不满足则标注为不平等上界。
4. **反樱桃挑选与 PoC 归因**：多重比较校正、选择性报告检测、基准 Goodhart 检测；把认证价格分解为安全/延迟/保守三项。

### 2.3 IP-65 TEMPORAL-CERT-SCHEDULER（时序证书调度器 TCS）
1. **交换率驱动优先级**：按 κ_j × 边际 margin/μs 排序，按谓词 L_φ 与运动 λ_o、λ_d 动态定价延迟。
2. **anytime 预算分配**：随机背包/贪心 + 抢占，满足周期与死线。
3. **双闸门与降级**：死线 + 新鲜度必须同时成立；超时走 anytime 降级或 fail-closed，绝不静默放行。
4. **与 CAR/LCS 集成**：调度决策写入租约依赖图，关键级冲突时安全优先。

## 3. 四层架构 v10（双根 + 基准审计）

```
根信任层（双根，并列）:
  真值根: IP-60 PSE → ω_t 层 → P_t 姿态盒 + ℓ_p 根租约
  时间根: IP-63 TCE → ω_L 层 → L̂_e2e 时序证书 + 死线租约 + κ_t 交换率
  双根合成: 联合证书 s=max(e_pose/r_max, L/L_max)；联合共形，禁止独立相乘
  任一失败 → 膨胀 P_max / 缩短租约 / fail-closed（级联）

L1: 几何图元/物体 6D → C_ms, B_t, L_m；人/多用户 → H_u（结论以 P_t 与 L_e2e 为条件）
L2: CTC + VLM + IP-35 仲裁 → 分支池；检索键含 ω、ω_L、护照
L3: IP-51 CAR(margin = min(查表, 租约@r_eff, persona) − L_φ·rad(P_t))
    → IP-49 □ 提升 → IP-47 组合（含延迟可加性）→ IP-39 规划
    → IP-45 总线(latency-cert/deadline-lease/anytime-cert) → IP-53 CMC 区间监控
调度: IP-65 TCS 按 κ_t × 边际 margin/μs 分配 anytime 预算；双闸门；高关键级凌驾
L4: IP-61 DCL(覆盖驱动采集 + 护照 + 分块加权共形)
    ← IP-62 CCA(覆盖红队 + 尾延迟红队 + 选择偏差 + 投毒 + 回归)
    → 重校准 r_ω / L̂ → IP-55 CKB + IP-54 SCV(退化 + 抖动仿真)
L5(离线/周期): IP-64 CCA-II(封存预注册基准 + 认证竞争比 + 信息对等 + 反樱桃 + PoC)
    → 输出「价格 of certification」与安全调整 Pareto，只读，不得改写运行策略
运行期: 分层 → 联合证书 → 谓词提升 → 调度 → 守卫；超时/退化/尾相关漂移 → 降级或停机
```

## 4. 实验设计（E103–E110 硬门槛，承接 E95–E102）

| 实验 | 指标 | 门槛 |
|---|---|---|
| E103 时序证书覆盖 | 各阶段/各 ω_L 的时延覆盖；端到端尾部覆盖；死线违约率 | ≥1−β；尾部 ≥1−β−2%；≤预注册目标 |

## 5. 本轮最大风险

**一句话**：时序证书与姿态证书都是概率保证，而**延迟尾部与不确定性尾部在难场景里正相关**（透明/镜面/遮挡/快动既慢又抖），一旦把「1−α_p」与「1−β」的独立覆盖率相乘当作联合覆盖，就会在安全关键的尾部系统性高估、静默不 sound，而竞品分析按均值报告恰好把这条尾部平均掉，使系统「平均更优、尾部失效」且难以察觉；因此 E105（双根联合覆盖/尾相关性）与 E109（基准独立性/反樱桃）必须设为红线，默认回退到「独立界取保守并集 + r_eff 扣减 + 纯查表/安全停机」这条永不高估的底线。

### IP-63 TCE：时序证书、时-不确定交换、联合证书、随时精化
```
def latency_certificate(stage_samples, stratum, beta):
    # 按层对执行时间做分块共形，直接对端到端样本校准（吸收阶段相关）
    q = blocked_weighted_quantile(stage_samples.e2e, weights(stratum), 1 - beta)
    return TemporalCert(bound=q, stratum=stratum, beta=beta,
                        n_eff=effective_sample_size(stage_samples),
                        eps_shift=shift_bound(stage_samples))

def temporal_soundness(pose_lease, L_e2e, H_act, phi, theta):
    r_eff = pose_lease.r0 + pose_lease.lam_o*(L_e2e+H_act) \
                          + pose_lease.lam_d*math.sqrt(L_e2e+H_act)
    deadline_ok  = L_e2e <= L_max(phi, theta)
    freshness_ok = r_eff <= r_max(phi, theta)
    return (deadline_ok and freshness_ok), r_eff

def exchange_rate(pose_lease, L_e2e, H_act, L_phi):
    t = L_e2e + H_act
    return L_phi * (pose_lease.lam_o + pose_lease.lam_d/(2*math.sqrt(t)))

def joint_certificate(pairs, stratum, gamma):
    # pairs = (e_pose, L_e2e)；禁止用两个独立分位数相乘
    scores = [max(e / r_max, l / L_max) for (e, l) in pairs]
    q = blocked_weighted_quantile(scores, weights(stratum), 1 - gamma)
    corr = tail_correlation(pairs)          # 难场景正相关，必须报告
    return JointCert(radius=q, gamma=gamma, corr=corr,
                     independent_product_invalid=(corr > CORR_EPS))

def refine_anytime(task, budget_us):
    # 单调精化：每步都维持“当前界是真实误差上界”
    cert = task.coarsest_sound_cert()
    for step in task.refinement_steps:
        if not step.fits(budget_us): break
        cand = step.apply(cert)
        if cand.is_sound() and cand.radius <= cert.radius:
            cert = cand                              # 单调不增
    return cert                                      # 任意中断点仍 sound

def safe_degrade_if_late(task, now, pose_lease, phi, theta):
    ok, r_eff = temporal_soundness(pose_lease, now - task.tau, H_act, phi, theta)
    if not ok:
        return FailClosed('temporal_invalid') or refine_anytime(task, MIN_BUDGET)
    return task.current_cert
```

### IP-65 TCS：交换率驱动的 anytime 调度
```
def certificate_scheduler(tasks, T_period, pose_lease):
    # 按“每微秒带来的认证 margin 增益”排序；κ_t 给延迟定价
    def value_per_us(t):
        kappa = exchange_rate(pose_lease, t.L_hat, H_act, t.L_phi)
        d_margin = t.marginal_margin_gain(1)          # 一单位预算的边际增益
        return kappa * d_margin
    ordered = sorted(tasks, key=value_per_us, reverse=True)
    budget = T_period
    plan = {}
    for t in ordered:
        if t.criticality >= K_SAFETY:
            # 安全关键：先满足死线+新鲜度双闸门，不足则降级/停机
            if budget < t.min_budget or not t.deadline_feasible():
                plan[t] = ('fail_closed', 0); continue
        gamma = allocate_under_deadline(t, budget)     # 随机背包/贪心
        plan[t] = ('anytime', gamma); budget -= t.time(gamma)
    return plan

def car_guard_v6(e, x, cert_obj, persona, lease_p, lease_c, t):
    theta = cert_obj.alpha_e[e] * cert_obj.theta_sim[e]
    L_e2e = cert_obj.time_cert[e].bound
    ok, r_eff = temporal_soundness(lease_p, L_e2e, cert_obj.H_act, e, theta)
    if (not ok) or x.stratum not in observed_strata:
        cascade_invalidate(cert_obj.lease_graph, 'pose_or_time')
        return FailClosed(tag='dual_root_invalid')
    m_lookup = cert_lookup_L0(x, stratum=x.stratum, tau_layer=x.tau_layer).m_lo[e]
    m_lease  = lease_c.m - lease_c.lam * (t - lease_c.tau)
    m_cap    = persona_cap[e](persona)
    m_dual   = cert_obj.L_phi[e] * geodesic_radius(cert_obj.pose_cert_at(r_eff))
    return min(m_lookup, m_lease, m_cap) - m_dual >= theta
```

### IP-64 CCA-II：认证竞争比、信息对等、反樱桃、PoC 归因

```
def certified_competitive_ratio(policy, oracle, benchmark, delta):
    ratios = [cost(policy, I) / cost(oracle, I) for I in benchmark]
    rho_hat = max(ratios)                              # 逐实例
    rho_ub  = empirical_bernstein_upper(ratios, delta) # 分布置信上界
    return CompetitiveReport(per_instance=rho_hat, upper=rho_ub)

def information_parity(policy, competitor, spec):
    diffs = {'sensors': spec.sensors(policy) - spec.sensors(competitor),
             'compute': spec.flops(policy) - spec.flops(competitor),
             'actuation': spec.actuation(policy) - spec.actuation(competitor),
             'timing_info': spec.timing(policy) - spec.timing(competitor)}
    return ParityReport(diffs=diffs, fair=all(d <= 0 for d in diffs.values()))

def anti_cherry_pick(runs, preregistered_metrics, alpha):
    # 主指标预注册；多重比较用 Holm 校正；报告全部运行
    raw = {m: p_value(m, runs) for m in preregistered_metrics}
    adjusted = holm_bonferroni(raw, alpha)
    cherry = detect_selective_reporting(runs, preregistered_metrics)
    return BenchmarkAudit(adjusted=adjusted, cherry_suspected=cherry,
                          reported_all=len(runs) > 0)

def price_of_certification(cert_cost, comp_cost, decomposition):
    poc = cert_cost - comp_cost
    return PoC(total=poc,
               safety=decomposition.safety,
               latency=decomposition.latency,
               conservatism=decomposition.conservatism)

def benchmark_goodhart(policy_history, benchmark_version):
    # 若策略针对该基准版本反复调参，则竞争比不再外推
    drift = divergence(policy_history, benchmark_version)
    return drift > DRIFT_MAX
```

| 竞品分析樱桃挑选/基准 Goodhart → 虚假优势 | 高 | E109 红线；封存预注册 + 隐藏层 + Holm 校正 + 全量报告 |
| 信息不平等（竞品有深度/力/触觉）→ 不公平比较 | 中-高 | 信息/测量对等审计；不平等标注为上界；PoC 归因 |
| anytime 过度降级 → 可用性崩塌或安全 margin 过紧 | 中-高 | 单调性 + 任意点 sound；关键级凌驾；可用性损失门槛（E106） |
| 调度器为省时间牺牲安全关键任务 → 饥饿 | 中-高 | 高关键级死线优先；双闸门；超时 fail-closed 而非降关键级 |
| 联合/时序校准数据同源 → 相关性被低估 | 中-高 | 数据护照（定义 47）+ 独立审计集（定义 49）；尾延迟红队 |
| 认证价格过高 → 产品不可用 | 中 | PoC 分解（安全/延迟/保守）；按谓词分级使用 □/◇；动态精度 |

## 6. 本轮最大风险

**一句话**：时序证书与姿态证书都是概率保证，而延迟尾部与不确定性尾部在难场景里正相关（透明/镜面/遮挡/快动既慢又抖），一旦把「1−α_p」与「1−β」的独立覆盖率相乘当作联合覆盖，就会在安全关键的尾部系统性高估、静默不 sound，而竞品分析按均值报告恰好把这条尾部平均掉，使系统「平均更优、尾部失效」且难以察觉；因此 E105（双根联合覆盖/尾相关性）与 E109（基准独立性/反樱桃）必须设为红线，默认回退到「独立界取保守并集 + r_eff 扣减 + 纯查表/安全停机」这条永不高估的底线。
