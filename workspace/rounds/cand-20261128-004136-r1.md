## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（价值对齐 → 我们一直在优化「示教像不像」，而榜单在算「价值高不高」）**
直觉：训练目标是模仿示教（行为克隆），但榜单的价值函数是 `V_off = g(成功率, 步骤分)`（F20），且官方还看延迟/动作规整度（F22）。示教编码的是「遥操作员当时怎么做的」（演示者的隐式价值），不等于「怎样最省步骤、最稳、最可信」（官方的显式价值）。这中间有一条**对齐鸿沟**：我们能把示教复现到 99%，却未必把 `V_off` 抬高——甚至可能因为模仿了示教里的冗余/慢动作而在步骤分上吃亏。价值对齐的解法不是再加模块，而是**把优化目标从「似然」搬到「价值」**：学一个评分价值模型，用它给数据加权、给动作重排、给每次发布设门禁。核心反直觉点：**在这场考试里，「更像示教」与「更高分」不是一回事，甚至可能负相关；只做行为克隆的队伍会系统性低估价值函数。**

严谨定义：令 π 为策略、τ 为轨迹、`V_off(τ)` 为官方价值（成功率与步骤分的聚合，聚合权重未知）、`C(τ)` 为安全/规整约束集（关节界、平滑、延迟稳定、无异常）、`H` 为人手介入信号。**价值对齐** ＝ 求 `min_π E_{τ~π}[-V_off(τ)]` s.t. `τ∈C`，且当 `H` 指示介入时 π 的行为须服从「让位/停持」的人本价值。定义**对齐鸿沟** `Gap = V_off* - V_off(π)`，以及**代理错配** `Mismatch = corr(L_imitation, V_off)`——若 `Mismatch≈0` 或为负，则「训得越像、分不一定越高」。

**灵感 2（持续学习 → 32 任务是一个稳定性-可塑性问题，而「多轮提测」是开发期持续学习）**
直觉：一个模型服务 32 任务、再叠加 110 语料共训、再叠合成示教——这就是典型的**多任务持续学习**：加新技能时旧技能会遗忘（灾难性遗忘），弱任务被强任务淹没（平均分被最弱任务支配，P1）。上一循环把 I2 的「负迁移」当风险，本轮把它**形式化**：负迁移就是「反向迁移 BWT<0」。更关键的是赛制给了持续学习真实舞台——**预约时段多轮提测**（F21）：开发是持续迭代的，但每次评测被冻结。于是正确框架不是「评测中在线学习」（违规），而是**开发期持续学习 + 冻结评测下的价值回归门禁**：每次新提交必须在抬升新能力的同时不降低旧任务价值。核心反直觉点：**持续学习在这里的产物不是「一个更强的模型」，而是一套「每次提交都不许退步」的发布纪律——BWT≥0 比 FWT>0 更值钱，因为平均分先被最弱任务拖死。**

严谨定义：设技能族 `F_1..F_m`，在数据增量 Δ（孪生/合成/新族）上更新得 π'。**持续学习合格** 当且仅当：(i) 前向迁移 `FWT = E_{新族}[V_off(π') - V_off(π)] > 0`；(ii) 反向迁移 `BWT = E_{旧族}[V_off(π') - V_off(π)] ≥ 0`（无遗忘）；(iii) 可塑性预算：新增容量/训练量按**边际价值** `∂V_off/∂compute` 分配到各家族，避免在饱和任务上浪费容量、在弱任务上欠拟合。

**两者统一**：价值对齐回答「优化的目标对不对」（把似然换成价值、防 specification gaming），持续学习回答「多任务/多轮更新会不会把已对齐的价值弄丢」（BWT≥0、防遗忘）。合起来是本循环主命题：**做一个「价值对齐的持续学习者」——每加一项技能，都在官方价值上可证地不倒退。** 上一循环的「数据引擎」是燃料，本循环的「价值门禁」是方向盘与刹车。

## 2. 对上一循环痛点的增量修订

- P1（弱任务支配平均）升级为 **P1'（价值-容量错配）**：容量/训练量未按边际价值分配，饱和任务过训、弱任务欠训——持续学习的可塑性预算问题。
- P2（泛化缺口）补价值维度：不仅「分布外动作错」，还「步骤分拿不全」（效率/里程碑对齐）。
- P5（时间压力）补充：成功率与步骤分双目标、聚合权重未知（F20 只证两项、未给公式）——目标本身欠定义，是价值对齐第一类风险（underspecification）。
- P6（部署）补充可信度：延迟波动与动作统计规律性被记录（F22），「规整」进入隐式价值。
- 新增 **P9（代理错配）**：行为克隆似然与 `V_off` 可能弱相关甚至负相关；不测 `Mismatch` 就不知道自己在优化什么。
- 新增 **P10（价值模型可被博弈）**：任何逆向出来的评分器都可能被策略「刷分」（触发里程碑而未完成任务），需独立真值校验。

## 3. 研究问题（本循环立项 Q9–Q11，Q1–Q8 保留）

- **Q9（价值模型可辨识性）**：从官方得分点（F17）+ 示教能多准地逆向 `V_off`？评分价值模型 Ŝ 与真实步骤分的偏差如何度量、阈值如何设才敢用于加权/重排/门禁？聚合权重（成功率 vs 步骤分）未知时，如何做鲁棒（minimax）对齐而非赌一个权重？
- **Q10（防博弈）**：如何用**独立真值校验器**（物体真实位移/终态配置/里程碑单调性）界定 Ŝ 的可博弈上界，保证「抬高 Ŝ」不脱离「抬高 V_off」？
- **Q11（对齐的持续学习）**：族级 LoRA 专家 + 价值门控路由能否在「加族不退步（BWT≥0）」下优于单一共训？边际价值容量分配（哪族多给 rank/epochs）能否把平均分洼地抬起来？多轮提测下，「价值回归套件」要多严才能既不误杀真进步、又拦住静默遗忘？

## 4. 设计原则（新增 PR6–PR7，其余保留）

- **PR6 价值优先律**：任何训练/推理改动先问「它抬高的是 `V_off` 还是只是 `L_imitation`」；无法给出 `V_off` 增益假设的改动不进 L2。与 PR5（数据杠杆）互补：PR5 管「这条数据教什么」，PR6 管「这次改动值不值分」。
- **PR7 不倒退发布律**：每次提交前跑价值回归套件；`BWT<0`（任一旧族价值下降超过噪声带）即阻断发布，除非有明确交换理由并记录在注册表。持续学习的默认约束是「不许忘」，不是「尽量学」。
- PR1–PR5 保留（上一循环 §4）。

## 6. 本轮最大风险（一句话）

**把逆向出来的评分价值模型 Ŝ 当成真值来对齐——Ŝ 与官方步骤分公式的任何偏差，都会被 RWR 加权、chunk 重排、发布门禁三处放大成系统性 specification gaming，而多轮持续学习会让这种偏差在「每次都通过门禁」中静默累积，最终榜单退步却查不出原因。**

# UniBot-V1 参赛创新点清单（第 1 轮 · 新循环 v2.0：价值对齐 × 持续学习）

> 检索日期：2026-11-26 / 11-27（上一循环）、**2026-11-28（本轮复核 README 与挑战页）**；来源见 §5。承接 v1.1：I1/I2/I5/I8/I9 深化，I4 升级，I7 修剪，新增 I10–I12。清单只增改不重置。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I1 考纲校准五轴增广引擎 ★★★★（维持 v2，补价值轴）
- 六要素同上一循环 v1.1（考纲卡按官方 5 轴校准增广）。
- **本轮补充**：增广不只对齐「视觉分布」，还要对齐**步骤分相关的时序/效率变化**（如把同一示教的冗余帧段裁剪、把里程碑前的停顿压缩）——即增广目标纳入 `V_off` 而非仅 `L_imitation`（PR6）。
- **风险**：效率增广可能破坏动作平滑性 → 与 I6 的动作规整回归联动。

### I2 数据引擎 3.0：价值加权 + 高价值回放 + 梯度手术 ★★★★★
- **动机**：上一循环用「进度效率×平滑度」启发式质量分加权（P8）；但真正要抬的是 `V_off`，不是启发式分数（P9）。孪生共训的负迁移需从「手调权重」升级为「可测的 BWT 控制」。
- **本轮深化（价值对齐 × 持续学习）**：
  1. **价值加权回归（RWR）**：离线训练评分价值模型 Ŝ（轨迹段 → 预测 0–100 步骤分），用 `w = exp((Ŝ-S_ref)/β)` 乘到 flow-matching 损失上，把容量从「低价值示教」挪向「高价值示教」——比启发式平滑度更贴官方目标。
  2. **高价值回放核心集**：每技能族保留一小撮「Ŝ 最高 + 多样性最大」的轨迹作 replay buffer；共训孪生/合成数据时按比例混入，**持续学习防遗忘**（用价值挑选「记住什么」）。
  3. **梯度冲突消解**：孪生共训时按族计算梯度，检测余弦冲突（<0）并用 PCGrad / 任务算术 / 自适应加权替代被官方忽略的 weight 配置（F11），直接压低 BWT<0 风险。
- **与现有方案差异**：均匀 BC / 启发式质量加权优化的是「像不像」；本点优化「值不值分 + 不忘旧技能」。
- **技术可行性**：高。Ŝ 用轻量时序模型（GRU/2 层 Transformer）在示教+里程碑标签上训；RWR 只改 loss 权重；PCGrad 在 loader patch 内实现。
- **所需资源**：Ŝ 训练 1 GPU 日/轮；replay buffer 磁盘 <200GB；训练仍 1×24GB 起步（F11）。
- **落地步骤**：①逆向得分点标签；②训 Ŝ 并在 3 任务上做校准曲线；③RWR 加权首轮共训；④构造回放核心集；⑤加 PCGrad 做孪生家族 L0 消融（对比 BWT）。
- **风险**：Ŝ 偏差被 RWR 放大（见本轮最大风险）→ 缓解：Ŝ 置信门控 + 高价值样本人工抽检；RWR 温度 β 从保守（近均匀）起步逐步收紧。

### I3 接触任务族关键点视觉伺服回退 ★★★★（维持）
- 六要素同 v1.1；本轮不深化，仅确认其作为「接触段价值」的载体，其关键点误差可作为 I8 的代理指标之一。

### I4 人本价值门控（原「人手干预感知门控」升级）★★★★
- **动机**：上一循环把它当「干扰处理」；价值对齐视角下，这是**人本价值**（安全/服从）与**任务价值**（完成/得分）冲突时的优先级问题。
- **本轮深化**：显式定义价值序：检测到人手介入 `H=1` → 触发「停持→让位→重估」，**安全与服从优先于完成**（PR3 升级为价值原则）；干预态短 chunk、稳定态长 chunk（v1.1 保留）。
- **与现有方案差异**：多数队伍只优化任务分，忽略「人机共存」的隐式价值（F22 可信度条款）。
- **可行性/资源**：高/低（同 v1.1：手部检测 + 历史栈，<50ms）。
- **风险**：误判介入导致频繁停摆 → 滞回 + 置信门控。

### I5 合成示教 + 得分点对齐恢复 ★★★★（v3：防博弈）
- 六要素同 v1.1（扰动重放 / 跨段缝合 / WMA 生成 / 得分点里程碑标注）。
- **本轮深化（防 specification gaming）**：里程碑检测器与「独立真值校验器」解耦——真值 = 物体真实位移/终态配置（分割 + VLM），**不依赖**里程碑检测器本身；只有「检测器判达标 ∧ 真值校验通过」的合成段才入训。这样刷分（触发里程碑但没真完成）无法污染标签。
- **风险**：真值校验器本身有误差 → 双门禁 + 人工抽检 5%。

### I6 确定性低延迟部署服务 ★★★★（维持，补规整回归）
- 六要素同 v1.1；**本轮补充**：把「动作统计规律性 + 延迟波动」加入 PR4 门禁（F22）——不只 p99<40ms，还要动作分布无异常尖峰，避免被可信度条款标记。

### I7 世界模型测试时前瞻 ★（修剪：仅作数据资产）
- **修剪理由**：测试时前瞻（O(1–2) 次 rollout）延迟与工程成本高；I10 的「价值批评家 + chunk 重排」用一次前向即可近似「择优」，性价比更高。
- **处置**：推理期前瞻**正式裁撤**；WMA-0 仿真模式（F15）仅保留为 I5 的合成数据引擎。

### I8 评测运营 + 对齐式持续学习门禁 ★★★★★（v3）
- **动机**：真机按时段稀缺（F21）+ 多轮迭代需防静默遗忘（P1'/P10）。
- **本轮深化**：
  1. **持续学习指标**：每次候选 π' 相对线上 π 计算 `FWT`（新族增益）与 `BWT`（旧族不倒退，带噪声带）；`BWT<0` 阻断发布（PR7）。
  2. **价值回归套件**：族分层 × {V_off、安全约束、动作规整、防博弈一致性} 四类检查；离线跑为主（复用 I1 增广器造偏移），L2 真机只测 top 候选（v1.1 分级保留）。
  3. **防博弈一致性**：`anti_hack_agreement = 1 - |Ŝ - 真值校验| 超阈比例`，>0.9 才准入。
  4. **注册表升级**：记录每次「离线预测增益 / FWT / BWT / 真机增益」，滚动 Spearman；相关性 >0.6 的代理才可单独准入 L2（v1.1 保留）。
- **可行性/资源**：高/低（离线为主 + 表格脚本）。
- **风险**：噪声带设太窄误杀真进步、太宽放过遗忘 → 用历史真机重复测量标定噪声带。

### I9 reset 期检索类比迁移 ★★★★（v2：非参数持续记忆）
- 六要素同 v1.1（reset 一次检索，物体嵌入→动作先验软注入）。
- **本轮补充（持续学习视角）**：检索库本质是**非参数记忆**——加新族/新物体只需往库里加条目，**零权重更新、零遗忘**，是 I11 参数隔离之外的互补路径；旧技能永远可被检索召回。
- **风险**：同 v1.1（误检索软门控 + 合规书面确认）。

### I10 价值批评家 + chunk 重排（新）★★★★
- **动机**：推理期想「择优」，但 I7 的 rollout 太贵；价值对齐给了更便宜的替代——一个能直接给动作 chunk 打分的 critic。
- **与现有方案差异**：普通策略每步只出 1 个 chunk；本点出 K 个候选，用离线 critic `Q(obs, chunk) → 预测 Ŝ` 加约束惩罚重排，取最高者执行——**测试时价值对齐（rejection sampling / best-of-K）**，不做动力学 rollout。
- **技术可行性**：中。critic 从示教段离线监督（输入 obs 嵌入 + 动作 chunk，输出后续步骤分），无需在线 RL；仅高风险节点启用重排以控延迟。
- **所需资源**：critic 训练 1–2 GPU 日；K=4 时推理延迟 ×K，仅高风险节点用。
- **落地步骤**：①critic 数据构造（(obs,chunk)→后续Ŝ）；②离线训 critic 并做校准；③重排门控（风险分类器决定是否启用）；④L0 消融（重排 vs 不重排的 Ŝ 与真值差）；⑤真机抽测。
- **风险**：critic 偏差与 Ŝ 同源 → 与 I5 真值校验共用独立 verifier；K× 延迟超预算 → 门控严格。

### I11 任务族 LoRA 专家 + 价值门控路由（新）★★★★
- **动机**：单一共训下族间梯度冲突导致遗忘（P1'/BWT<0）；价值-容量错配（饱和族过训、弱族欠训）。
- **与现有方案差异**：单 LoRA 全任务混训 vs 共享冻结 VLM 基座 + **族级 LoRA**（pick-place / contact-insertion / pour / deformable / articulation / stacking）。加新族＝加适配器、旧适配器冻结 → **BWT≈0 由构造保证**；路由按指令+首帧选族（或 top-2 软混合）。
- **边际价值容量分配**：按每族 score headroom（`V_off` 距满分差）分配 LoRA rank 与训练步数——把容量给弱族洼地，而非平摊。
- **技术可行性**：中。官方支持 VLM/DiT LoRA（F11）；单 checkpoint 含多适配器＝一个模型（PR2 待书面确认）；若被判多模型，用 TIES/DARE 合并为单一 LoRA（降级预案）。
- **所需资源**：适配器训练仍单卡起步；多适配器显存小（冻结基座共享）；部署时按族加载或合并。
- **落地步骤**：①族划分表（LLM 初筛+人工）；②训 2 族最小原型测 FWT/BWT；③加价值路由；④边际价值分配 rank；⑤全 32 任务族化 + 合并/隔离合规确认。
- **风险**：路由错族伤分 → 软混合 + 置信回退到基座；单模型边界裁定 → 合并降级预案。

### I12 评分细则宪法提示（新）★★★
- **动机**：`observation.language` 只有一句任务指令（F23），模型不知道官方评分细则；价值对齐最便宜的一招是让它「读到价值函数」。
- **与现有方案差异**：纯 BC 策略仅凭视觉+短指令；本点在推理期把逆向的每任务评分细则作为「宪法」内部拼进语言条件（**不改变对外 observation.language，零权重更新**），使生成显式对齐步骤分结构。
- **技术可行性**：高（纯 prompt 工程）；风险是模型对长 rubric 不敏感 → 先 L0 验证。
- **所需资源**：极低（细则文本 + prompt 模板）。
- **落地步骤**：①逆向每任务细则文本；②内部拼 prompt；③L0 消融（有/无 rubric 的 Ŝ）；④无增益则并入 I1 提示模板。
- **风险**：长上下文稀释指令 / 模型忽略 rubric → 结构化短 rubric（bullet 化）。

### 1.1 价值模型 + RWR 加权（I2 v3）

```python
class ScoreValueModel:                      # 轻量时序模型: 轨迹段 -> 预测步骤分(0..100)
    def train(self, demos, rubric_labels):  # rubric_labels: 得分点里程碑逆向 + 人工抽检
        ...

def rwr_weight(seg):                        # 价值加权回归: 均匀 BC -> 按价值指数加权
    s = score_model.predict(seg)            # 0..100
    return math.exp((s - S_REF) / BETA)     # BETA 从大(近均匀)逐步收紧

def flow_loss(policy, seg):
    return (rwr_weight(seg) * flow_matching_loss(policy, seg)).mean()
```

### 1.2 价值批评家 + chunk 重排（I10）

```python
class ValueCritic:                          # (obs_embed, action_chunk) -> 预测后续 Ŝ
    def __call__(self, obs, chunk): ...

def get_action(self, obs):
    chunks = self.vla.sample_chunks(obs, K=4)          # K 候选
    if not self.risk_gate(obs):                        # 仅高风险节点重排
        return chunks[0]
    def score(c):
        return self.critic(obs, c) - self.constraint_penalty(c, obs)  # 价值 - 约束惩罚
    return max(chunks, key=score)
```

### 1.4 对齐式持续学习发布门禁（I8 v3）

```python
def aligned_release_gate(pi_new, pi_old, suite):
    for fam in suite.families:                         # 旧族: 不许忘
        bwt = eval_Voff(pi_new, fam) - eval_Voff(pi_old, fam)
        assert bwt >= -NOISE_BAND[fam], f"regression on {fam}: {bwt}"
        assert safety_ok(pi_new, fam)
        assert action_regularity_ok(pi_new, fam)       # F22: 延迟波动/动作规整
        assert anti_hack_agreement(pi_new, fam) > 0.9  # Ŝ 与独立真值一致
    assert fwt(pi_new, suite.new_fams) > 0             # 新族: 要有前向迁移

def anti_hack_agreement(pi, fam):                      # 独立真值: 物体真实位移/终态
    agree = []
    for ep in heldout(fam):
        s_hat  = score_model.predict(ep.traj)
        s_true = true_success_verifier(ep)             # 不依赖里程碑检测器
        agree.append(abs(s_hat - s_true) < EPS)
    return mean(agree)
```

## 2. 实验设计（价值对齐 + 持续学习协议 v3）

| 指标 | 定义 | 用途 |
|---|---|---|
| `Gap` | `V_off* - V_off(π)`（真机或代理） | 绝对价值缺口 |
| `Mismatch` | `corr(L_imitation, V_off)` | 检测「像≠高分」（P9） |
| `FWT` | `E_{新族}[V_off(π') - V_off(π)]` | 新技能前向迁移 |
| `BWT` | `E_{旧族}[V_off(π') - V_off(π)]` | 旧技能遗忘（发布门禁） |
| `Hack` | `1 - anti_hack_agreement` | 评分模型可博弈度（P10） |

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0 | Ŝ 校准曲线；RWR 温度扫描；I11 族隔离 BWT；I10 重排 Ŝ 增益；I12 rubric 有无 | 离线（免费） | Ŝ 与人工步骤分 Spearman>0.6；BWT≥0；重排 ΔŜ>0 |
| L1 | 2^(k-p)：{RWR, replay, PCGrad, rubric} 部分析因；{族 LoRA vs 单 LoRA} | 离线 + 少量真机 | 主效应显著 ≤3 组合进 L2 |
| L2 | top 组合真机确认：≥2 族 × 各 2 次 | 预约时段（稀缺，F21） | 真机增益 ≥ 离线预测 50%；无族退步 |
| 门禁 | PR4 + PR7：run_client 全流程、p99<40ms、动作规整、BWT≥0 | 本地 stub + 离线 | 0 拒绝动作、0 族回归 |

**首批 L2 排队**：①I11 族 LoRA 2 族原型（FWT/BWT）→ ②I2 v3 RWR 首轮 → ③I10 重排高风险节点抽测 → ④I12 rubric 提示抽测。
