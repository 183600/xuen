# 第 70 轮（承接第 69 轮「FLUID-RAS 交互消歧闭环」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「服务设计」×「实时控制」）

> R69 给闭环装上了一张「嘴」：面对歧义，它会看、会触、会问。但 R69 的 VoI 是一个**静态标量**，隐含三个从未被检验的假设：**交互瞬时完成、答案永远有效、被问的人无限耐心**。真实世界里，答案可能在决策承诺点之后才到（价值为负），可能在承诺前很久就到而**过期**（世界已漂移），而人是有容量、会疲劳、需要被尊重的**服务提供者**——每问一次都在消耗一份「服务预算」。于是 R69 在错误的时刻、以错误的渠道、按错误的耐久度使用了正确的信息论工具。
>
> 本轮两个灵感正好补上被忽略的维度：
> - **实时控制**把「时间」变成一等公民：截止期、延迟分位、抖动、自触发调度，把交互价值写成 `VoI(g,t)`——**到达概率 × 保鲜折扣 − 成本**；
> - **服务设计**把「交互」从原子动作升级为**服务接触点**：服务蓝图（前台/后台/支撑/证据）、服务等级目标（SLO）、容量与排队、公平与体验、以及服务失败后的**服务恢复**。
>
> 核心命题：**交互不是「问不问」，而是「在何时、经哪条渠道、对谁、以多高新鲜度去问」。把每个信息动作绑定到承诺点 D 与延迟分位 L_q，用自触发调度取「最晚仍可靠的时刻」t\*，用 SLO＋准入控制把服务时延翻译成控制质量 QoC；SLO 一旦越界就诚实地承认失败并退回 R68，绝不冒充准时。** 命名 **KAIROS-RAS**（Kairos-Aware Interactive Real-time Service for Risk-Adaptive Steering）——kairos 即「恰当时机」，而非 chronos 的线性时间。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证、还能问什么」，R70 问「**什么时候问最值、问得太晚还算不算数、被问的人受不受得了**」——不确定性不只是刹车踏板，也是一件必须在截止期前送达、并且保鲜的**服务**。

## 0. 直觉与动机

**灵感 1（实时控制 → 信息有截止期，也有保鲜期）**
直觉：一条在转向完成之后才到达的「左边有人」毫无价值；一条在路口前 10 秒就拿到、但世界已变化的路况同样会误导。信息的价值不是常数，而是一条**在承诺点 D 前达到峰值、之后归零**的曲线。实时控制教会我们两件事：把「完成时刻」当作硬约束（deadline），把「延迟」当作有分布、会抖动、可测量的对象（latency/jitter）。于是 R69 的 `VoI(g)` 必须升级为 `VoI(g,t)`：只有在 `t+L ≤ D` 时才有到达概率，且到达越早、离承诺越远，保鲜折扣 `e^{−κ(D−t−L)}` 越低。

**灵感 2（服务设计 → 交互是服务旅程上的接触点）**
直觉：服务设计从不把「一次客服电话」看作孤立事件，而看作**服务蓝图**的一部分：前台接触点（用户看到什么）、后台动作（内部如何处理）、支撑流程（系统/资源）、物理证据（收据、日志）。R69 的注视/探针/问句，正是前台接触点；信念更新与证据纪律是后台；MINT/FMA/MCG 是支撑；J 证书是物理证据。更关键的是，服务有**容量**与**关系**：人一次只能回答有限问题，被反复打扰会降低回答质量、增加延迟、抬高欺骗率。**过度提问是一个在单次 VoI 最优下依然发生的服务失败。**

**灵感 3（自触发 → 最优交互时刻是「最后可行时刻」）**
直觉：R69 一检测到 `U_epi > τ` 就问，这等价于高频轮询。但若不确定性随时间增长、信息随时间贬值，那么等待只会让「值得问的东西更多」且「答案更保鲜」——直到逼近可靠性边界。因此最优策略是**恰好在截止前问到**（just-in-time / kairos），而不是越早越好。自触发控制正是这么做的：不从固定周期触发，而是用当前状态**算出下一个触发时刻**。这把交互从「事件反应」变成「计划性服务预约」。

**灵感 4（多渠道 → 「看还是问」就是「选哪条服务渠道」）**
直觉：服务设计里，自助机响应快但能力浅，人工柜台能力强但排队久。R69 的三种信息动作恰好构成延迟—信息量谱系：注视最快、信息最少；探针居中；语言问句最慢、信息最多、社交成本最高。当截止期很紧时，最优解会自动**降级到低延迟渠道**（来不及问，就先看一眼）；当时间充裕时，才值得排那条慢而信息多的队。渠道选择与触发时刻因此必须**联合优化**，而不是先选动作再排时间。

**灵感 5（时间也是攻击面 → 新增时序威胁模型）**
直觉：一个会按截止期行动的系统，最脆弱的不是答案错，而是**时间被操纵**：对手用「慢回答」让答案永远迟到（可用性攻击），用「队列洪泛」抢占共享人类容量饿死受害者，用「快而错」通过延迟门却在门内注入错误（SLO 博弈），用「给时正确、承诺时失效」的新鲜度投毒。因此本轮必须交付准入控制、公平分配、SLO 审计与服务失败证书——**让系统能证明自己没有假装准时。**

## 1. 形式化定义（增量：定义 310–327）

**定义 310（KAIROS-RAS 总览与四不变式）** KAIROS-RAS = (T-VoI, SST, SBP, SLO, QCG, IAC, FSA, SR, FDM, K-MINT, RAS-WM‡)。四不变式：
(i) **实时流零学习写操作**（继承 R69 定义 293-i）；
(ii) **时限不变式**：任何信息动作 g 必须携带承诺点 D 与延迟分位 L_q，只允许在 `t ≤ D − L_q` 发起；错过即视为服务失败并走服务恢复；
(iii) **服务不变式**：交互必须满足 SLO 向量（延迟/中断率/新鲜度/公平/体验），任一越界即触发服务恢复与审计；
(iv) **证据纪律继承**（R69 定义 293-iii）——时限不放松证据要求，只决定证据能否在承诺前到达。

**定义 311（时间索引价值 T-VoI）** 设承诺时刻 D、模态身份随机变量 M、当前信念 b_t(M)。信息动作 g 在 t 发起、延迟 `L ~ F_L(g,ρ)`（随渠道与负载 ρ），观测 y。定义
`VoI(g,t) := IG(g;b_t) · E_L[ 1{t+L ≤ D} · e^{−κ(D−t−L)} ] − c_int(g,t)`，
其中 `IG(g;b_t) = H(M|o_t) − E_y[H(M|o_t,y)]` 为信息增益，κ>0 为新鲜度衰减率，`e^{−κs}`（年龄 `s = D−t−L`）为保鲜折扣，c_int 为物理/社交/服务成本。**关键性质：时间不是加性成本，而是对信息价值的乘性折扣，加上到达概率的硬截断。** R69 的 VoI 恰为 `κ=0、L=0、D=∞` 的退化。

**定义 312（延迟模型与服务渠道）** 每条信息渠道 `ch ∈ {gaze, probe, ask}` 有延迟分布 `F_L(·|ch,ρ)`、信息增益 `IG_ch` 与成本 `c_ch`；其中 ρ 为共享人类/传感器资源负载。渠道延迟排序 `L_gaze < L_probe < L_ask`，信息量排序通常相反。端到端延迟 `L = L_human + L_compute`（后者含 FMA 0.4ms 等确定性预算）。**「看还是问」被统一为「选哪条服务渠道」。**

**定义 313（承诺点与决策截止期）** 每个控制决策有承诺点 D（动作必须提交的时刻，如避障最后转向点、抓取闭合前、进入路口前的停车距离临界）。D 之前可交互、可等待；D 之后动作冻结、只保留 R68 认证。D 由 R67 VISTA 的未来危险视界与 R68 C-RAS-WM 的安全时间窗共同给出：`D = min(D_task, D_safe)`。

**定义 314（服务蓝图 SBP）** 一次交互建模为服务过程 `SBP = (front, back, support, evidence)`：front 为面向人类/环境的接触点（注视/探针/问句）；back 为信念更新、证据纪律、C-RAS-WM 安全认证；support 为 K-MINT 求解、FMA 第二意见、MCG 校准门、队列与准入；evidence 为 J_KAIROS 证书与交互日志哈希（可审计的「物理证据」）。蓝图每节点带时延与失败模式，交互可靠性定义为**端到端 SLO 满足**，而非单点动作成功。

**定义 315（服务等级目标 SLO 向量）** `SLO = (SLO_lat, SLO_int, SLO_fresh, SLO_fair, SLO_exp)`：
`SLO_lat: P(L ≤ L_max) ≥ 1−ε_L`；`SLO_int: 交互数/单位时间 ≤ r_max 且 ≤ 1 次/决策`；`SLO_fresh: s = D−(t+L) ≤ s_max`；`SLO_fair: Jain 指数 J(attn) ≥ F_min`（多主体共享人类时）；`SLO_exp: 人类信任/疲劳评分 ≥ E_min`（VQAuditor 回灌）。任一越界 = 服务失败（定义 322）。

**定义 316（自触发调度 SST）** 设不确定性截止期 `D_U(t) = t + (1/ρ_U)·ln(U_crit / U_epi(t))`（由定义 317 的增长界），决策截止期 D。调度器不周期轮询，而计算**最晚仍可靠的发起时刻**
`t* = min(D, D_U(t)) − L_{1−ε}(ch*, ρ)`，
在 `t = t*` 自触发；若当前 `t ≥ t*` 立即发起。渠道 ch* 由 K-MINT（定义 323）在到达约束内选增益/成本最优者。**这就是 kairos：不是越早越好，而是最晚仍来得及。**

**定义 317（新鲜度衰减与不确定性增长界）** 无交互时 epistemic 不确定性满足增长界 `U_epi(t+Δ) ≤ U_epi(t)e^{ρ_U Δ} + β`（ρ_U 由 R67 视界漂移与可观测性给出，β 为过程噪声注入）；信息年龄 s 引入残余界 `U_epi^res ≤ U_epi(t+L) + γ s`（γ 为世界漂移对判断的侵蚀率）。二者共同把「时间」翻译成「风险」。

**定义 318（控制质量 QoC）** `QoC(t) := 1/(1+U_epi^res(t))`（等价的归一化风险形式 `QoC = 1 − ΔR/ΔR_max`）；`QoC ≥ Q_min ⇔ ΔR ≤ ΔR_max`。QoC 是 SLO 与控制安全之间的桥：把服务时延与新鲜度折算成可度量的控制性能。

**定义 319（交互队列与容量）** N 个决策主体共享渠道 ch；到达率 λ、服务率 μ(ch)、负载 `ρ = λ/μ`；等待时间 `W ~ F_W(·|ρ)`，实际延迟 `L = W + L_exec`。**关键事实：`L_{1−ε}(ρ)` 在 `ρ→1` 时爆炸**，故服务容量直接决定控制可行性——容量是硬边界，不是软成本。

**定义 320（准入控制与 EDF 交互调度 IAC）** 请求 i 带截止期 D_i、服务时间假设 L_i，按截止期优先级。准入：仅当加入后满足 `ρ ≤ ρ_max`（ρ_max 由 `L_{1−ε}(ρ) ≤ L_max` 反解）且 EDF 可调度判据（utilization / demand-bound）成立才接纳；未接纳者立即走自身 R68 兜底并记录。EDF 执行已接纳请求。**准入既是实时调度，也是时间维度 DoS 的隔离墙。**

**定义 321（公平服务分配 FSA）** 多主体共享人类注意力，分配向量 attn_i，`J(attn) = (Σattn_i)² / (N·Σattn_i²) ≥ F_min`；采用 max-min 加权的 EDF（紧迫度 × 权重），既保截止期又防饿死。

**定义 322（服务恢复 SR）** 当 SLO 越界、截止期错过、队列不可调度、或检测到延迟异常：撤销本次交互的「已消解」结论，令 U_epi 未消解并走 R68 纯保守；生成**服务失败证书**（失败节点、延迟分位、QoC 缺口、SLO 违例维度）；对体验 SLO 越界记录「关系损伤」。**不能冒充准时。**

**定义 323（时间感知 MINT：K-MINT）** `(g*,t*) = argmax_{g∈𝒜_info, t≤D} VoI(g,t)`，s.t. `P(t+L(g,ρ) ≤ D) ≥ 1−ε`、`s(g,t) ≤ s_max`、`risk(g) ≤ ε_int`、准入通过、预算未越。若无可行的 (g,t) 或 `max VoI ≤ c`：不交互，走 R68。**渠道选择使「看现在 vs 稍后问」成为同一个优化里的两个候选解。**

**定义 324（时序投毒干扰集 ℰ_time）** 慢回答 DoS（拖延使答案迟到）、队列洪泛（抢占容量饿死受害者）、SLO 博弈（快而错以过延迟门却注入错误）、新鲜度投毒（给时正确、承诺时已失效）。并入 AIC：`ℰ_KAIROS = ℰ_FLUID × ℰ_time`。

**定义 325（证书 J_KAIROS）** `J_KAIROS = (J_FLUID, latency_p99, staleness_at_commit, qoc_min, fairness_J, schedule_hash, slo_status, kairos_ver)`。`Valid ⇔ Valid(J_FLUID) ∧ SLO 满足 ∧ 于 t* 发起 ∧ 证据纪律满足 ∧ 准入合规`。

**定义 326（截止期感知风险缩放）** `λ = max(efs_risk_scale, λ_floor(U_ale + U_epi^res))`，其中 `U_epi^res` 随距 D 的剩余时间与 SLO 缺口增大；若服务恢复触发，额外 `λ ≥ λ_recover` 且 `k ≤ k_cal_shrink`。保证「越接近承诺点，未消解歧义越被当作 aleatoric」。

**定义 327（严格包含链）** 当 `D=∞、κ=0、L=0、ρ→0、SLO 松弛` 时，KAIROS 逐指令退化为 FLUID-RAS（R69）；再令 `VoI ≤ c` 处处成立则退化为 CALM-RAS（R68）。即 **R68 ⊂ R69 ⊂ R70**：每一层都是上一层在「关闭新维度」边界上的严格退化，安全侧永不外扩。

## 2. 关键算法骨架

```python
# IP-265 T-VoI：时间索引信息价值（到达概率 × 保鲜折扣 − 成本）
def temporal_voi(g, t, D, belief, kappa, latency_dist, cost):
    ig = info_gain(g, belief)
    discount = expectation(latency_dist, lambda L:
                 (1.0 if t + L <= D else 0.0) * exp(-kappa * max(0.0, D - t - L)))
    return ig * discount - cost(g, t)

# IP-266 SST：自触发——算「最晚仍可靠」的发起时刻，不周期轮询
def next_trigger(U_epi, rho_U, U_crit, D, latency_dist, eps, now):
    D_U = now + log(U_crit / max(U_epi, EPS_FLOOR)) / rho_U   # 不确定性截止期
    Lq  = quantile(latency_dist, 1 - eps)                       # 延迟上分位
    return min(D, D_U) - Lq                                     # kairos 触发点

# IP-323 K-MINT：渠道 × 触发时刻联合优化；无利可图即退化 R68
def k_mint(g_cands, now, D, belief, budget, queue):
    best = None
    for g in g_cands:                                     # gaze / probe / ask
        for tt in trigger_grid(now, D, g):                # 含 JIT 点 t*
            if not budget.allow(g) or not c_ras_wm.certify_info(g): continue
            if not queue.admissible(g, tt, D):            # IP-270 准入
                continue
            score = temporal_voi(g, tt, D, belief, KAPPA, queue.latency(g), cost)
            if best is None or score > best.score:
                best = (g, tt, score)
    return best if best and best.score > 0 else None      # VoI<=c → 不问

# IP-270/321 准入 + 公平
def admit(req, queue, rho_max, F_min):
    if queue.load_after(req) > rho_max:          return False   # 容量硬边界
    if not edf_schedulable(queue.with_(req)):    return False   # 实时可调度
    if projected_jain(queue.attn.with_(req)) < F_min: return False
    return True

# IP-269 QCG：时延/新鲜度折算 QoC；不足则服务恢复
def qoc_guard(U_ale, U_epi_res, lam_base, remaining, qoc_min):
    U_floor = U_ale + U_epi_res
    lam = max(lam_base, lam_floor(U_floor))
    if qoc_projected(U_floor, remaining) < qoc_min:
        lam = max(lam, LAM_RECOVER)               # IP-272 服务恢复
    return lam

# IP-264 KAIROS 主闭环（继承 R69，插入时序-服务层）
def KAIROS_round(M, obs, now):
    z, o = M.mtm.forward(obs); c, U_cal, _ = M.cof.step(...)
    D = min(M.vista.deadline(), M.c_ras_wm.safe_window(o))     # 承诺点
    if now < M.sst.next_trigger(M.last_U_epi, ...) and M.k_mint.cached is None:
        return conservative_step(M, z, o, D)                   # 未到 kairos，不打扰
    K = 1 if M.fmp.mode_head(z) < TAU_MODE else 4
    U_ale, U_epi, modes, _ = M.aud.decompose(M.fmp.sample(o, K), z, M.fmp.mode_head)
    sel = M.k_mint.choose(modes, now, D, M.budget, M.queue)    # (g,t) or None
    U_epi_res = U_epi
    if sel is not None:
        g, t, _ = sel
        ans = M.cia.execute(g)                                 # 认证 + 证据纪律
        U_epi_res = M.cia.update_belief(modes, ans, staleness=D - (now + t))
    else:
        M.sr.note("no_voi_or_infeasible")
    lam = M.qcg.lambda_for(U_ale, U_epi_res, D - now)          # QoC 门控
    if M.sr.triggered:
        lam = max(lam, LAM_RECOVER)
        k   = min(k, M.c_ras_wm.shrink(U_cal))
    mode = select_mode(modes, U_epi_res, lam)
    tau  = M.pi_sigma.prefix_dispatch(mode.a[:k]) * lam
    M.qauditor.submit_async(sel, D, lam, M.slo.status(), M.sr.certificate())
    return k, lam, mode, (U_ale, U_epi_res)
```

## 3. 推导

**引理 19（最晚可行即最优：kairos 触发）** 设 VoI 如定义 311，延迟有硬上界 `L ≤ L_max`（渠道超时截断，A99），承诺点 D 固定，`IG(g)>0、κ≥0`。则在可行域 `t ≤ D−L_max` 内，折现因子 `e^{−κ(D−t−L)}·1{t+L≤D}` 关于 t 逐样本单调不减，故 VoI 关于 t 单调不减，最优触发取可行域上界 `t* = D − L_max`。若延迟无硬界，施加可靠性约束 `P(t+L≤D) ≥ 1−ε`，则 `t* = D − L_{1−ε}`。即**最晚仍可靠的时刻最优**；「尽早问」被「恰好在截止前问到」严格支配，支配量恰为新鲜度收益 `IG·(e^{−κ s_早} − e^{−κ s_晚})`。系：κ 越大、L 越大，R69 的「检测到就问」越次优。

**引理 20（新鲜度—控制质量界）** 由定义 317 的 `U_epi^res ≤ U_epi(t+L) + γs` 与风险对不确定性的 Lipschitz 性（继承 R69 A98）得承诺点风险增量 `ΔR ≤ L_R·(U_epi(t+L) + γs)`。要 `QoC ≥ Q_min ⇔ ΔR ≤ ΔR_max`，等价于新鲜度上界
`s ≤ s_max := (ΔR_max/L_R − U_epi(t+L)) / γ`。
故 SLO_fresh 给出一条**可计算的新鲜度约束**，与到达约束共同定义可行调度窗口；窗口为空 ⇒ 该渠道不可行 ⇒ 换更低延迟渠道（定义 312）或服务恢复。系：**截止期越紧，越应选低延迟渠道，而非高信息量渠道。**

**引理 21（自触发的中断率上界）** 若 `U_epi` 满足增长界（定义 317，ρ_U 为增长上界），则从 `U_low` 长到 `U_crit` 至少需 `Δ_min = ln(U_crit/U_low)/ρ_U`，故长度 T 的窗口内交互次数 `≤ 1 + T/Δ_min`。与固定周期轮询（周期取最坏情况 Δ_min^worst）相比，自触发在不确定性增长慢的时段自动延长间隔，故**期望中断率 ≤ 周期策略，最坏情况相等**。系：SLO_int 可用 ρ_U 上界离线校验，得到硬中断率保证。

**引理 22（容量—可行性与准入的充分条件）** 渠道延迟分位 `L_{1−ε}(ρ)` 关于 ρ 单调增，令 `ρ_max = sup{ρ : L_{1−ε}(ρ) ≤ L_max}`。若准入维持 `ρ ≤ ρ_max`，则所有已接纳交互满足 SLO_lat；EDF 可调度判据 `Σ L_i/p_i ≤ 1` 保证截止期；max-min 加权 EDF 使 `J(attn) ≥ F_min` 且饿死时间有界。系：**服务容量是控制可行性的硬边界**——负载逼近 1 时延迟分位爆炸，控制回路必须在准入层就拒绝而非在控制层补救。

**定理 18（QoC 保证与服务恢复的安全性）** 在 A99–A101 下，若准入维持 `ρ ≤ ρ_max` 且按 t\* 自触发，则承诺点 `QoC ≥ Q_min` 以概率 `≥ 1−ε_L−ε_s` 成立；当可行窗口为空或 SLO 不可满足时服务恢复触发，λ 单调不降，动作退化为 R68 认证前缀，故风险 ≤ R68。因此 KAIROS 的 QoC 保证是「有前提、可审计」的，且前提失效时安全侧不会更差。

**定理 19（严格包含链 R68 ⊂ R69 ⊂ R70）** 令 KAIROS 参数为 (D,κ,L,ρ,SLO)。当 `D=∞、κ=0、L=0、ρ→0、SLO 松弛` 时，K-MINT 的解 `(g*,t*)` 退化为 `(argmax_g[VoI(g)−c(g)], now)`，逐指令等于 R69 的 MINT；再令 `VoI ≤ c` 处处成立则退化为 R68。极限路径上两者行为差 = 0，故新层是旧层在「关闭时间/服务维度」边界上的严格退化，安全侧不外扩、只获得效率侧的 resolution bonus。

**定理 20（时序 DoS 的隔离上界）** 设对手控制比例 φ 的请求且无限拖延。在准入控制与每主体配额下，受害者交互延迟被限制在由 `ρ_max` 决定的分位内，故受害者 QoC 缺口 `≤ ε_Q(φ_reserved)` 且不随 φ 增大；未被接纳的攻击请求只消耗自身 R68 兜底，不能挤占受害者容量。系：把「时间」纳入 SLO 并以准入隔离，等价于给控制回路预置了一条**带宽/时延预留通道**。

## 6. 本轮最大风险

**一句话**：KAIROS 的全部时序保证押在「**延迟分布与不确定性增长率是平稳且已知**」这一前提上——一旦延迟模型被慢回答攻击或负载漂移打破、或不确定性增长被低估，自触发就会算晚，系统将在「**自认为赶上了截止期**」的错觉里，带着过期或缺失的证据做出承诺——**误判自己准时，比承认迟到更危险**。

**次级风险与缓解**：
1. **延迟模型失配**（人类响应分布漂移）→ 在线分位估计 + 保守上分位 + 服务失败证书回灌（定义 322、325）；
2. **不确定性增长被低估**（D_U 算晚）→ 用 ρ_U 上界而非点估计，且 SLO_fresh 双保险（引理 20）；
3. **时序 DoS / 队列洪泛** → 准入控制 + 每主体配额 + 公平 EDF（定义 320、321；定理 20）；
4. **SLO 博弈（快而错）与新鲜度投毒** → 证据纪律继承 + staleness 加权 + ℰ_time 对抗训练（定义 323、324）；
5. **过度设计的服务开销** → K=1 常规路径与 R69 持平，只有临近截止期才启用 K-MINT 全搜索；SLO 松弛时逐指令退化（定理 19）。

```python
# IP-265 T-VoI：时间索引价值
def temporal_voi(g, t, D, belief, kappa, latency_dist, cost):
    ig = info_gain(g, belief)
    discount = expectation(latency_dist, lambda L:
                 (1.0 if t+L <= D else 0.0) * exp(-kappa*max(0.0, D-t-L)))
    return ig*discount - cost(g, t)

# IP-266 SST：最晚仍可靠的发起时刻（kairos）
def next_trigger(U_epi, rho_U, U_crit, D, latency_dist, eps, now):
    D_U = now + log(U_crit/max(U_epi, EPS_FLOOR))/rho_U
    return min(D, D_U) - quantile(latency_dist, 1-eps)

# IP-323 K-MINT：渠道 × 时间联合优化
def k_mint(g_cands, now, D, belief, budget, queue):
    best = None
    for g in g_cands:
        for tt in trigger_grid(now, D, g):
            if not budget.allow(g) or not c_ras_wm.certify_info(g): continue
            if not queue.admissible(g, tt, D): continue
            score = temporal_voi(g, tt, D, belief, KAPPA, queue.latency(g), cost)
            if best is None or score > best.score: best = (g, tt, score)
    return best if best and best.score > 0 else None     # 无利可图 → R68

# IP-270/321 准入 + 公平
def admit(req, queue, rho_max, F_min):
    if queue.load_after(req) > rho_max:            return False
    if not edf_schedulable(queue.with_(req)):      return False
    if projected_jain(queue.attn.with_(req)) < F_min: return False
    return True

# IP-269 QCG：QoC 门控 + 服务恢复
def qoc_guard(U_ale, U_epi_res, lam_base, remaining, qoc_min):
    U_floor = U_ale + U_epi_res
    lam = max(lam_base, lam_floor(U_floor))
    if qoc_projected(U_floor, remaining) < qoc_min:
        lam = max(lam, LAM_RECOVER)
    return lam

        U_epi_res = M.cia.update_belief(modes, ans, staleness=D-(now+t))
    lam = M.qcg.lambda_for(U_ale, U_epi_res, D-now)
    if M.sr.triggered:
        lam = max(lam, LAM_RECOVER); k = min(k, M.c_ras_wm.shrink(U_cal))
    mode = select_mode(modes, U_epi_res, lam)
    tau  = M.pi_sigma.prefix_dispatch(mode.a[:k]) * lam
    M.qauditor.submit_async(sel, D, lam, M.slo.status(), M.sr.certificate())
    return k, lam, mode, (U_ale, U_epi_res)
```

## 4. 推导

**引理 19（最晚可行即最优：kairos）** 在硬延迟上界 `L≤L_max`（A99）下，可行域 `t≤D−L_max` 内折现因子关于 t 单调不减，故最优触发 `t*=D−L_max`；无硬界时在 `P(t+L≤D)≥1−ε` 下 `t*=D−L_{1−ε}`。即「最晚仍可靠的时刻」最优，「尽早问」被严格支配，支配量 = 新鲜度收益 `IG·(e^{−κs_早}−e^{−κs_晚})`。

**引理 20（新鲜度—控制质量界）** `ΔR≤L_R(U_epi(t+L)+γs)` ⟹ `QoC≥Q_min ⇔ s≤s_max=(ΔR_max/L_R−U_epi(t+L))/γ`。SLO_fresh 给出可计算新鲜度上界；窗口为空则换低延迟渠道或服务恢复。系：截止期越紧越应选低延迟渠道。

**引理 21（自触发中断率上界）** ρ_U 为增长上界 ⇒ 最小间隔 `Δ_min=ln(U_crit/U_low)/ρ_U` ⇒ T 内交互次数 `≤1+T/Δ_min`；期望中断率 ≤ 周期策略，最坏情况相等。

**引理 22（容量—可行性充分条件）** `ρ_max=sup{ρ:L_{1−ε}(ρ)≤L_max}`；准入维持 `ρ≤ρ_max` ⟹ SLO_lat 满足；EDF `ΣL_i/p_i≤1` 保截止期；max-min 加权 EDF 保 `J≥F_min` 且饿死有界。

**定理 18（QoC 保证与服务恢复安全性）** A99–A101 下，准入 + t\* 自触发 ⟹ 承诺点 `QoC≥Q_min` 概率 `≥1−ε_L−ε_s`；窗口为空/SLO 不可满足 ⟹ 服务恢复，λ 单调不降、退 R68 认证前缀，风险 ≤ R68。

**定理 19（严格包含链 R68⊂R69⊂R70）** `D=∞、κ=0、L=0、ρ→0、SLO 松弛` ⟹ K-MINT 退化为 R69 MINT（逐指令相同）；再 `VoI≤c` ⟹ 退化为 R68。极限路径行为差 = 0。

**定理 20（时序 DoS 隔离上界）** 对手控制比例 φ 且无限拖延；准入 + 每主体配额 ⟹ 受害者延迟被限制在 ρ_max 决定的分位内，QoC 缺口 `≤ε_Q` 且不随 φ 增大；未接纳请求只耗自身兜底。

## 7. 本轮最大风险

**一句话**：KAIROS 的全部时序保证押在「**延迟分布与不确定性增长率是平稳且已知**」这一前提上——一旦延迟模型被慢回答攻击或负载漂移打破、或不确定性增长被低估，自触发就会算晚，系统将在「**自认为赶上了截止期**」的错觉里，带着过期或缺失的证据做出承诺——**误判自己准时，比承认迟到更危险**。

**次级风险与缓解**：延迟模型失配（在线分位估计 + 保守上分位 + 失败证书回灌）；不确定性增长低估（用 ρ_U 上界 + SLO_fresh 双保险）；时序 DoS/洪泛（准入 + 每主体配额 + 公平 EDF）；SLO 博弈与新鲜度投毒（证据纪律继承 + staleness 加权 + ℰ_time 对抗训练）；过度设计（K=1 常规与 R69 持平，仅临近截止期启用 K-MINT 全搜索，SLO 松弛时逐指令退化）。
