## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（技能组合 → 32 个任务不是 32 个技能，而是十几个原语的长程排列）**
直觉：看任务名就知道它们共享大量原语——HangCup、StoreCups、StackBowls 共享「接近-抓取-搬运-放置」；ZipUp、Unlock、RemovePinnedNote 共享「接触-施力-释放」；PlugCharger、PlugInEthernet、SyringeWaterTransfer 共享「对准-插入」。一个端到端 VLA 在每条示教上独立学这些组合，等于把同一套原语重复学 32 遍，且**组合边界**（抓取后何时该抬、对准后何时该插）没有被显式监督。更关键：官方得分点（F17/F25）本质就是官方技能分解——它把每个任务拆成若干里程碑，我们却只拿它做评测，不拿它做训练与运行时的文法。**反直觉点：技能组合的正确单位不是「任务」也不是「独立技能策略」，而是「共享同一模型权重的技能相位」；组合不是运行时拼接多个模型，而是让单一模型在相位条件下产生组合行为。**

**灵感 2（中间件 → 平均成功率排序下，中间件是「下尾乘数」）**
直觉：榜单按平均成功率排序（F21），一个任务失败一次就是 1/320 的固定损失；32 个任务里只要有几个长程任务频繁「差一点」，平均分就被下尾拖死。而中间件恰好作用在下尾：它不提升策略的上限，而是把「差一点的失败」变成「擦线成功」——在技能边界处截断重规划、在进度停滞时触发恢复、在块内提前制动、在超时前保底提交。它还是**唯一能在不改权重、不违反单模型规则的前提下**插入的杠杆（F20/F23）。**反直觉点：中间件的目标不是让策略更强，而是让策略的失败变得可计分、可回滚、可恢复；它优化的是成功率分布的左尾，不是均值。**

**两者合流：得分点即技能文法，中间件即文法解释器。**
官方得分点给出每任务的技能里程碑序列；技能段重组把 32k+110 语料变成「原语词典 + 组合语法」；中间件在运行时维护「当前处于哪条产生式、下一个里程碑是什么、是否该回退」，并把单一模型的输出约束在这条文法上。**本轮结论：前两轮押「数据引擎」仍对；但数据引擎产出的是「技能词典」，要把它变成分数，还缺一个运行时的「文法解释器」——这就是 I10/I11。**

## 2. 严谨定义：带技能相位的半马尔可夫决策过程与确定性中间件

### 2.1 任务即技能文法

对任务 τ，令技能序列 \(s_{1:K}\)、边界 \(0=b_0<\cdots<b_K=T_\tau\)。每个技能
\[
s=(I_s,\pi_s,\beta_s,[d_s^{\min},d_s^{\max}])
\]
分别是 initiation set、intra-skill policy、termination condition、时长区间。官方得分点 \(g_1<\cdots<g_M\) 是文法上的里程碑，通常 \(M\le K\)；建立单调对齐 \(a:\{b_k\}\to\{g_m\}\)。一个组合任务的合法执行是文法的一条产生式：
\[
\tau \Rightarrow s_1 s_2 \cdots s_K,\qquad \mathrm{post}(s_k)\models \mathrm{pre}(s_{k+1})
\]
其中 pre/post 用可观测谓词近似（物体在夹爪内、物体在目标区域内、插头进入端口、物体高度超过支撑面等）。**关键：这套文法是官方给的，不是我们发明的；它把「得分点」从评测指标变成可监督的中间表示。**

### 2.2 单模型相位条件策略

\[
\pi_\theta(a_t,z_t\mid o_{\le t},l),\qquad z_t=(s_t,\rho_t)
\]
\(s_t\) 为技能令牌，\(\rho_t\in[0,1]\) 为技能内进度。硬约束：所有技能共享同一组权重 \(\theta\)，不按任务/技能加载不同 checkpoint（F20）。\(z_t\) 的来源有三档：
- **硬条件**：中间件直接给 one-hot \(s_t\)；
- **软条件**：给相位信念 \(b_t(s)\) 的嵌入；
- **自预测**：模型辅助头输出 \(\hat z_t\)，中间件只做门控。

三档的鲁棒性排序是 Q10 的实验对象。直觉上软条件最稳，硬条件最强但最脆，自预测最省事但把风险藏在模型内部。

### 2.3 中间件作为确定性转录器

\[
M_\phi:(o_{1:t},\pi_\theta,C)\mapsto(a_{t:t+T_a-1},\hat z_t,\text{telemetry}_t)
\]
约束：
1. **无可学习参数，或参数属于 \(\theta\)**（同一 checkpoint 的辅助头）；不引入第二个学习模型；
2. **每步延迟 \(L\le L_{\text{budget}}\)**，且 \(L\) 的方差有界（F23）；
3. **episode 局部状态**，N 端口隔离（F22）；
4. **对同输入确定**（可复现）。

因此中间件是「单模型的确定性外壳」，不是「多模型路由器」。这条定义直接决定 I10 的形态，也决定 I3/I9 必须改成同源特征。

### 2.4 相位信念与调度目标

由于无力/触觉（F8），边界不可直接观测。用文法约束的 HMM：
\[
b_t(s)\propto p(e_t\mid s)\sum_{s'}A_{s,s'}\,b_{t-1}(s')
\]
\(A\) 由技能文法约束（只允许自环、下一技能、恢复边），\(e_t\) 是可观测边界证据（夹爪状态跳变、EE 速度剖面、动作 chunk 不连续性、进度头平台、物体位移）。调度是带承诺的选项选择：
\[
\max_{\{\text{switch times}\}}\ \mathbb{E}\Big[\sum_{m}w_m\mathbb{1}[\text{hit }g_m]-\lambda T-\mu\sum_t\mathbb{1}[\text{switch}_t]\Big]
\]
\(\mu\) 抑制抖动（chattering），\(\lambda\) 抑制超时。承诺规则：只有当 \(b_t(s')>\tau\) 且当前技能驻留 \(d\ge d_{\min}\) 时才切换；否则保持。硬切换是 \(b_t\) 退化为 one-hot 的特例，也是最大风险来源。

### 2.5 合规判据（三闸的可操作版本）

- **计分轴**：每个中间件动作必须能映射到「提高某任务成功率」或「提高某任务步骤分」；不能映射的复杂度一律删除（PR1）。
- **单模型**：权重唯一；外壳无学习或同源；无在线学习。独立的 DINOv2/CLIP/开放词汇检测器属于第二个模型，是合规负债（修正 I9/I3）。
- **部署预算**：15Hz 下 p99 < 66ms；中间件自身 ≤5ms；不增加 GPU 峰值显存。

## 3. 对第 2 轮痛点的增量修订

- **P1（弱任务洼地）→ 失败类型分解**：把失败分为 A 感知/接近、B 抓取/接触、C 技能边界、D 长程停滞、E 超时、F 人为干扰；中间件只治 C/D/E/F，A/B 仍归数据与 I3/I5。**先测失败类型分布，再决定中间件预算。**
- **P5（时间压力）**：F21 确认排序以成功率为先、步骤分为平局；中间件的优先级是「保成功」而非「多拿步骤分」；超时前保底提交比冒险多做一个技能更划算。
- **P6（部署）**：F24 确认 chunk 固定；「自适应 chunk」必须改为「固定 \(T_a\) + 块内有效视界 \(k\le T_a\) + 安全填充」，否则违规。
- **P8（示教质量）**：技能段重组要求段级质量分，不只是 episode 级；低质段（犹豫、抖动、重复）在重组前剪掉。
- **新增 P9（外部编码器合规）**：I3/I9 原方案使用独立检测器/编码器，与 F20 的「单一模型」存在解释风险；改为复用同一 checkpoint 的中间层特征或模型内辅助头。
- **新增 P10（组合错误不可回滚）**：长程任务中一个技能失败会污染后续所有技能；没有触觉/力反馈时，边界错误只能靠视觉进度与动作统计检测。中间件的核心价值就是**在污染扩散前截断**。

## 4. 研究问题（本轮立项 Q9–Q12，Q1–Q8 保留）

- **Q9（技能文法的可观测性）**：在没有力/触觉的条件下，用哪些信号（夹爪状态、EE 速度剖面、动作 chunk 不连续性、进度头平台、视觉物体位移）能以多高精度检测技能边界？边界 F1 与组合成功率的相关性有多强？
- **Q10（相位条件的鲁棒性）**：把相位作为硬条件、软嵌入、还是辅助头自预测，哪种在相位误判下退化最小？训练期「相位 dropout」能否让策略对中间件错误免疫？
- **Q11（技能段重组的物理可行性）**：跨任务替换技能段时，如何用仿真（Isaac Lab，F14）与可达性/碰撞检查过滤不可行组合？重组数据的正迁移边界在哪里？
- **Q12（中间件的收益归因）**：在固定权重下，中间件带来的成功率增益中，多少来自边界截断、多少来自停滞恢复、多少来自超时保底？如何用 L0 相位噪声注入预注册这些增益？

## 5. 设计原则（新增 PR6–PR7，其余保留）

- **PR6 文法优先于模块**：能用「同一模型的相位条件 + 确定性调度」解决的组合问题，不要引入第二个模型或运行时模块切换（合规 + 延迟双重理由）。
- **PR7 下尾优先**：中间件的每次改动先问「它是否降低了灾难性失败的概率」，而不是「它是否提升了平均动作质量」。与 PR1（计分轴）互补：PR1 管做什么，PR7 管先救什么。
- PR1–PR5 保留（第 1/2 轮 §4）。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I1 v3 考纲校准 + 边界感知增广引擎 ★★★★★
- **动机**：第 2 轮按官方 5 轴校准增广，但扰动是「整条轨迹均匀施加」；真实失败集中在技能边界（抓取瞬间、放置瞬间、插入瞬间），均匀增广把预算浪费在稳定段。
- **与现有方案差异**：从「考纲卡」升级为「考纲卡 + 边界卡」：对每任务标注技能边界窗口，扰动剂量在边界附近放大 2–3×，稳定段只做轻扰动；增广后的片段必须仍满足技能文法的 pre/post 谓词，否则丢弃。
- **技术可行性**：高。边界来自 I11 的分割管线；增广是纯数据工程；文法校验用轻量进度头 + 规则。
- **所需资源**：1×24GB GPU（官方默认微调，F11）；增广输出约 2TB；1 人周。
- **落地步骤**：①在 3 个任务上标边界，验证边界卡模板；②实现边界窗口扰动算子；③文法一致性过滤；④L0 剂量-响应；⑤扩到 32 任务。
- **风险**：边界标注噪声（缓解：多信号投票 + 人工抽检 5%）；边界增广破坏可行性（缓解：pre/post 谓词 + 仿真碰撞检查）。

### I2 v3 数据引擎 2.0：技能词典共训 + 技能族平衡采样 ★★★★★
- **动机**：第 2 轮按「任务孪生」入训 110 语料；但跨任务可迁移的单位其实是**技能段**，不是整个任务。任务级孪生会漏掉「不同任务共享同一原语」的大量数据。
- **与现有方案差异**：三件事升级：
  1. **技能族平衡采样**：按技能族（抓取-搬运、插入、旋转/拧、拉链/折叠、倾倒、堆叠）而非任务名采样；32 考题全量 + 技能族内其他任务按相似度加权。
  2. **段级质量加权**：每条示教先切段（I11），低质段（犹豫、抖动、重复）降权或剪除，而不是整条 episode 一起加权。
  3. **评测 schema 对齐**：只用评测可用键（F24）；训练若依赖评测缺失的键，静默丢信息。
- **技术可行性**：高（LoRA/frozen-VLM 单卡起步，F11；全参 action expert 4–8 卡）。
- **所需资源**：技能族子集 ≈1–2TB + 32 任务 ≈2TB；训练 1×24GB 起步、8×A100 上限。
- **落地步骤**：①技能族表（§1）；②段级质量分；③loader patch（技能族权重 + 段权重）；④batch 频率单测；⑤首轮共训；⑥族级 L0 正/负迁移。
- **风险**：负迁移（同族但动态相反，如 ZipUp vs Unzip）；段分割错误污染权重；相机配置不一致（先抽样核对 4 相机命名/分辨率）。

### I3 v2.1 接触任务族关键点视觉伺服回退 ★★★★（合规修正）
- **动机**：插入/按压类任务（PlugCharger、PlugInEthernet、SyringeWaterTransfer）失败集中在最后 1–2cm 的接触段，纯端到端策略方差大。
- **与现有方案差异**：第 2 轮用开放词汇检测器做关键点，属于第二个学习模型，与 F20「单一模型」存在解释风险。v2.1 改为：
  - 优先复用**同一 checkpoint 的 VLM 中间层特征/注意力**做关键点定位；
  - 若必须训练检测头，则作为**模型内辅助头**，与动作头共享 backbone；
  - 触发由 I10 的技能相位驱动（只在接触相位激活），不再全局运行。
- **技术可行性**：中。取决于官方模型是否暴露中间层特征（大概率可）；关键点回归头训练成本低。
- **所需资源**：无额外模型；1 人周工程 + 1 GPU 日/任务族。
- **落地步骤**：①确认中间层特征接口；②关键点辅助头/注意力可视化；③接触相位触发 + 滞回；④低置信回退到端到端；⑤L0 消融。
- **风险**：中间层特征定位精度不足（缓解：多尺度特征 + 几何一致性）；组委会仍认定辅助头为第二模型（降级预案 I3'：只做训练时辅助监督，推理纯端到端）。

### I4 v2 人手干预门控 + 块内有效视界 ★★★★（接口修正）
- **动机**：人为干扰是官方评测的一部分（F20）；第 2 轮的「自适应 chunk」与 F24 冲突——`action_chunk_size` 在 metadata 固定，不能逐 episode 改。
- **与现有方案差异**：不改接口，改为**固定 \(T_a\) + 块内有效视界 \(k\le T_a\)**：
  - 稳定态 \(k=T_a\)（8–16）；
  - 干预/高不确定态 \(k=4\text{–}6\)，其余步填安全保持/制动动作；
  - 边界临近时由 I10 截断 chunk，提前重规划。
- **技术可行性**：高。纯执行层改造，无需重训。
- **所需资源**：1 人周工程；本地 `run_client` 时序实测。
- **落地步骤**：①实测 evaluator 的 chunk 消费语义（逐 step 还是整块开环）；②干预状态机 + 安全填充；③边界截断；④L0 干预注入；⑤单任务通道抽测。
- **风险**：若 evaluator 整块开环执行，块内有效视界只能靠动作内容实现——首次调用就必须保守，不能依赖中途重规划。

### I5 v3 非标称示教合成 + 得分点对齐恢复 ★★★★（升级）
- **动机**：数据集全成功、无失败示教；恢复能力只能靠合成。第 2 轮已做扰动重放/跨段缝合，但恢复动作的「入口」不明确。
- **与现有方案差异**：恢复 = **从失败技能的边界重入**：用 I10 的相位信念判断失败发生在哪个技能，回到该技能的 initiation set，重放该技能及其后续，而不是从头重来或手工写恢复原语。合成数据按技能文法门禁：只有达成下一得分点的片段才保留。
- **技术可行性**：中-高。扰动重放与缝合是纯数据工程；边界重入依赖 I11 的分割。
- **所需资源**：1×24GB GPU；数据工程 2 人周；检测器 1 GPU 日/任务族。
- **落地步骤**：①得分点逆向；②3 个弱任务（PlugCharger/ZipUp/PourOutMedicine）试点；③边界扰动 + 重入；④文法门禁；⑤LoRA 增量训练；⑥单任务通道 A/B。
- **风险**：合成偏离分布与真实失配（缓解：扰动幅度从考纲卡采样）；边界误判导致重入错误技能（缓解：置信门控 + 只在高置信时合成）。

### I6 v2 中间件就绪的确定性低延迟部署服务 ★★★★
- **动机**：N 端口并发（F22）、每步延迟与抖动被记录（F23）、共享 backend 不得互相阻塞。
- **与现有方案差异**：从「能跑」升级为「有 SLA」：
  - 每步 deadline 调度（p99 < 40ms，给 15Hz 留余量）；
  - 每端口独立队列 + episode 状态隔离；
  - 动作健康检查（界内、平滑、无异常外推）；
  - 抖动抑制（预分配、CUDA Graph、避免运行时分配）；
  - 健康探针 + 断线重连；
  - 结构化 telemetry（相位、停滞、截断、延迟）供 I8。
- **技术可行性**：高。复用官方 model_server 的 msgpack/websocket 模式（F12）。
- **所需资源**：2×A100 80G 共享 backend；每端口 1 CPU 核；1 人周。
- **落地步骤**：①deadline 调度器；②端口隔离与并发压测；③动作健康；④telemetry schema；⑤混沌测试（断线、慢请求、坏 obs）。
- **风险**：并发争用导致 p99 抖动；量化/编译引入动作异常——用 `run_client` 全流程回归门禁。

### I7 世界模型测试时前瞻 ✂（裁撤推理路径）
- **裁撤理由**：测试时 rollout 延迟高，难以塞进 66ms 预算；WMA 作为第二个模型与 F20 的单模型边界存在解释风险；其收益未被证实。
- **资产去向**：WMA-0 仿真模式（F15）转为 I5/I11 的**离线数据生成器**，不进入推理路径。裁撤不等于废弃。

### I8 v3 评测运营闭环 + 技能级消融注册表 ★★★★
- **动机**：真机通道稀缺；待验证组合爆炸；第 2 轮的代理指标只到 episode 级，无法定位「哪个技能边界出了问题」。
- **与现有方案差异**：新增三类指标与一类实验：
  1. **技能边界 F1**（±0.5s 容差）；
  2. **组合成功率**（多技能任务的整链成功率，区别于单技能成功率）；
  3. **相位噪声注入**（以概率 ε 随机翻转相位令牌，测中间件鲁棒性）；
  4. **失败类型分解**（§5）与**中间件收益归因**（边界截断/停滞恢复/超时保底各贡献多少）。
- **技术可行性**：高（L0 纯离线）。
- **所需资源**：1 人周；注册表 = 表格 + 脚本。
- **落地步骤**：①指标实现；②注册表 schema；③首个用例 = I10 相位噪声注入；④L0/L1/L2 分级；⑤预注册预期增益。
- **风险**：离线-在线相关性建立慢（缓解：先用 3–4 个已知真机结果回填）。

### I9 v2 reset 期同源技能感知检索 ★★★★（合规修正 + 深化）
- **动机**：未见物品轴（同类不同外观）在 32 任务 × 2/10 次中全面出现；纯参数化泛化对新外观方差大。
- **与现有方案差异**：第 2 轮用 DINOv2/CLIP 外部编码器，属于第二个模型；v2 改为：
  - 用**同一 checkpoint 的 VLM 特征**建索引（合规）；
  - 检索单位从「整条 episode」改为「当前技能段」：先由 I10 解析任务文法，再按技能+物体可供性检索该技能的抓取参数/接近方向/插入姿态；
  - 先验只做软偏置 + 距离阈值门控，超阈退回无先验。
- **技术可行性**：中-高。同源特征可能不如专用编码器判别性强，但合规且零额外模型。
- **所需资源**：FAISS 索引；1 人周；无额外 GPU 模型。
- **落地步骤**：①同源特征提取；②技能段索引；③reset 检索 + 缓存；④软先验注入；⑤L0 未见轴测试；⑥真机抽测。
- **风险**：同源特征对「同类不同外观」不敏感（缓解：拼接几何描述词/可供性向量）；误检索伤标称任务（缓解：软偏置 + 阈值）；合规解释需书面确认。

### I10 技能相位中间件（新） ★★★★★
- **动机**：长程任务的下尾失败集中在技能边界与停滞；不改权重、不引入第二个模型，就能把「近失」变成「擦线成功」。
- **与现有方案差异**：现有方案要么端到端黑箱（无边界概念），要么运行时切换多个技能策略（违反单模型/增加延迟）。I10 是**单模型的确定性外壳**：
  - 解析任务文法（来自指令 + 官方得分点）；
  - HMM 维护相位信念（文法约束转移）；
  - 选项调度（承诺 + 滞回，抑制抖动）；
  - 边界截断（chunk 内提前重规划）；
  - 停滞检测 + 边界重入恢复；
  - telemetry 供 I8。
- **技术可行性**：高。全部是 CPU 规则/小矩阵运算，O(K²)，K≈5–10。
- **所需资源**：每端口 1 CPU 核；1–2 人周；无额外 GPU。
- **落地步骤**：①文法表（§1）；②边界证据；③HMM；④调度器；⑤块内仲裁；⑥进度账本；⑦L0 相位噪声注入；⑧L2 真机 A/B。
- **风险**：相位误判 + 硬承诺 → 错误技能锁定（缓解：软条件 + 承诺 + 相位 dropout + 超阈退回单体策略）。

### I11 技能段重组数据引擎（新） ★★★★
- **动机**：32k+110 语料是技能词典；任务级训练没有显式利用「同一技能在不同物体/任务间复用」。
- **与现有方案差异**：把示教切成技能段，做**段级重组**：
  - 替换：把任务 A 的「抓杯子」段替换为任务 B 的同技能段；
  - 拼接：A 的接近段 + B 的抓取段 + C 的放置段；
  - 边界扰动：在技能边界扰动状态并重放后续（生成恢复数据）；
  - 重复/换序：堆叠数量变化、独立技能换序（组合长度泛化）。
  - 物理可行性过滤：IK 可达、碰撞检查（Isaac Lab，F14）、可供性类匹配、进度一致性。
- **技术可行性**：中-高。分割是主要难点；重组是数据工程。
- **所需资源**：数据工程 2 人周；仿真过滤 1 GPU 日；段库约 100GB。
- **落地步骤**：①分割管线（§3）；②段级质量分；③段库 schema；④重组算子；⑤可行性过滤；⑥L0 正迁移；⑦LoRA 增量训练。
- **风险**：分割错误（缓解：多信号 + 人工抽检）；不可行组合（缓解：仿真过滤 + 拒绝率监控）；负迁移（缓解：族内替换 + 低权重起步）。

### I12 单模型技能令牌条件化（新） ★★★
- **动机**：I10 的相位若只作为外部调度信号，模型内部仍可能「不配合」；把技能相位条件进模型，能让同一组权重产生更一致的组合行为。
- **与现有方案差异**：在单一 checkpoint 上加**技能令牌辅助头 + 相位进度头 + 边界头**，用 FiLM/前缀 token 把技能嵌入注入 action expert；训练期做**相位 dropout**（以概率 p 把真值令牌替换为模型自预测或均匀分布），让策略对中间件误判免疫；用软标签（分割信念）而非硬 one-hot。
- **技术可行性**：中。需要改训练代码，但仍是单模型、单前向。
- **所需资源**：1×24GB LoRA 起步；1–2 人周；无额外推理模型。
- **落地步骤**：①加辅助头；②条件注入；③软标签 + 相位 dropout；④L0 对比硬条件/软条件/自预测；⑤决定是否保留。
- **风险**：相位标签噪声；条件化在误判时反而伤性能（缓解：dropout + 软条件 + 与 I10 规则调度做 A/B；若不如 I10 则降级为可选）。

## 2. 关键产物 B：技能相位中间件（I10）

### 2.1 架构（每 episode 一个实例，端口隔离）

```
obs ──► ObsAdapter ──► PhaseTracker(HMM) ──► Scheduler(options)
          │                    ▲                    │
          │                    │                    ▼
          └──► Model πθ ──► aux heads ──► ChunkArbiter ──► ActionGuard ──► chunk
                    (same checkpoint)          │
                                               ▼
                                         ProgressLedger ──► Recovery
                                               │
                                               ▼
                                           Telemetry ──► I8
```

关键点：`PhaseTracker` 用**上一步**前向得到的 aux heads（边界/进度）+ 当前本体信号更新信念，再条件当前步前向——一步延迟在 15Hz 下可忽略，且不需要额外前向。

### 2.2 HMM 相位跟踪（文法约束）

```python
class PhaseTracker:
    def __init__(self, grammar, tau=0.7, d_min=3):
        self.g = grammar                 # [R, G, L, T, A, REL]
        self.K = len(grammar)
        self.A = grammar_transition(self.g)  # 自环 + 下一技能 + REC 边
        self.b = prior_from_instruction(grammar)  # reset 期一次
        self.k = 0
        self.dwell = 0
        self.tau, self.d_min = tau, d_min

    def evidence(self, obs, prev_aux, prev_chunk):
        # 全部来自本体/上一步 aux，无额外视觉模型
        dg  = abs(obs.gripper - prev_obs.gripper)              # 夹爪跳变
        dv  = norm(obs.ee_vel - prev_obs.ee_vel)               # 速度剖面
        dch = chunk_discontinuity(prev_chunk)                  # 动作块不连续
        dpr = abs(prev_aux.progress - prev_prev_aux.progress)  # 进度平台
        dobj = visual_object_displacement(prev_obs, obs)       # 可选，轻量
        return np.array([dg, dv, dch, dpr, dobj])

    def update(self, e):
        # 观测模型：边界证据越大，越倾向切换；用预标定的 logistic
        lik = boundary_likelihood(e)          # shape (K,)
        self.b = normalize(lik * (self.A @ self.b))
        s_hat = int(np.argmax(self.b))
        # 承诺：后验足够高且驻留足够久才切换
        if self.b[s_hat] > self.tau and s_hat != self.k and self.dwell >= self.d_min:
            self.k, self.dwell = s_hat, 0
        else:
            self.dwell += 1
        return self.k, self.b.copy()
```

`grammar_transition` 只允许三类边：自环（停留）、`k→k+1`（正常推进）、`k→k` 或 `k→k-1` 的 REC 边（恢复）。这避免了「未抓取就搬运」这类非法跳转，也把搜索空间压到 O(K)。

### 2.3 调度与块内有效视界

```python
class SkillMiddleware:
    def get_action(self, obs):
        e = self.tracker.evidence(obs, self.prev_aux, self.prev_chunk)
        k, b = self.tracker.update(e)

        z = self.model.skill_embed(k, b)          # 软条件：同一 checkpoint
        chunk = self.model.propose_chunk(obs, z=z)  # 固定 T_a

        # 边界临近 → 截断 chunk，下一调用提前重规划
        if self.tracker.boundary_imminent(b, k):
            k_eff = min(self.T_a, self.boundary_eta(obs, chunk))
        else:
            k_eff = self.T_a if self.ledger.stable() else self.K_MIN

        chunk = self.guard.pad_safe(chunk, k_eff)  # 其余步填保持/制动
        self.ledger.update(obs, k, b, chunk)

        if self.ledger.stalled(window=W):
            self.recovery.reenter(k)               # 从技能边界重入
        self.prev_chunk, self.prev_aux = chunk, self.model.last_aux
        return chunk
```

`boundary_eta` 用「预计还有多少步到边界」：若小于 \(T_a\)，只执行到边界前一步，避免把「抓取后抬升」和「搬运」混在一个开环块里。这是中间件对长程组合最直接的贡献。

### 2.4 延迟预算（15Hz，单步 ≈66ms）

| 组件 | 预算 | 备注 |
|---|---|---|
| ObsAdapter（resize/缓存/历史栈） | 3ms | 只处理声明的键（F24） |
| PhaseTracker（HMM + 证据） | 1–2ms | O(K²)，K≈5–10 |
| Model πθ 前向（含 aux heads） | 35–45ms | 单模型、单前向 |
| ChunkArbiter + ActionGuard | 2ms | O(1) |
| 传输（msgpack/websocket） | 5ms | 复用官方模式（F12） |
| 余量（p99 抖动） | 8–10ms | F23 要求延迟稳定 |
| **合计** | **<66ms** | 目标 p99 <40ms |

### 2.5 合规检查（提交前硬门禁）

- [ ] 只有一个 checkpoint；无按任务/技能加载不同权重。
- [ ] 中间件无独立学习模型；检测器是规则或同源辅助头。
- [ ] episode 内无权重更新、无评测分布记忆；reset 期只做一次解析/检索。
- [ ] 每端口独立状态；共享 backend 并发无阻塞（F22）。
- [ ] 动作健康：界内、平滑、无异常外推；延迟方差有界（F23）。
- [ ] 若组委会认定「辅助头/中间层特征」仍属第二模型 → 降级为纯规则中间件（I10-lite），不阻塞主链。

## 3. 关键产物 C：技能段重组数据引擎（I11）

### 3.1 分割管线

输入：episode（4 相机、关节/EE/夹爪、动作、语言）、任务文法。
输出：技能段库 `SkillSegment(task, skill, object, affordance, start, end, quality)`。

```python
def segment_episode(ep, grammar):
    ev = boundary_evidence(ep)                 # 同 §2.2，离线可多用视觉信号
    cand = change_points(ev, penalty=PEN)      # CUSUM / PELT
    bounds = align_to_grammar(cand, grammar)   # 单调对齐（DTW / 动态规划）
    segs = []
    for i in range(len(bounds) - 1):
        s = SkillSegment(
            task=ep.task, skill=grammar[i],
            object=detect_object(ep, bounds[i]),
            affordance=affordance_vector(ep, bounds[i]),
            start=bounds[i], end=bounds[i+1],
            quality=segment_quality(ep, bounds[i], bounds[i+1]),
        )
        segs.append(s)
    return [s for s in segs if s.quality > Q_MIN]
```

`segment_quality` 由四部分组成：平滑度（动作二阶差分）、时长合理性（与文法先验区间比）、进度单调性（进度头不倒退）、无重复（不自循环多次）。低质段在重组前剪掉，避免把犹豫/抖动学进策略。

### 3.2 重组算子

```python
def recompose(lib, task, rng):
    g = task_grammar(task)                    # 例如 [R,G,L,T,A,REL]
    out = []
    for skill in g:
        # 只在同可供性类内替换，避免负迁移
        pool = [s for s in lib[skill]
                if affordance_dist(s.affordance, task_affordance(task)) < D_MAX]
        if not pool:
            return None
        out.append(rng.choice(pool))
    # 拼接处状态必须衔接
    if not stitchable(out):
        return None
    if not feasible_in_sim(out):              # Isaac Lab：IK + 碰撞
        return None
    if not progress_consistent(out):          # 进度头单调 + 命中预期得分点
        return None
    return stitch(out)
```

五个算子：
1. **替换（substitute）**：同技能、不同物体/任务，扩展可供性覆盖。
2. **拼接（splice）**：A 接近 + B 抓取 + C 放置，生成新的长程组合。
3. **边界扰动（perturb）**：在段边界扰动物体/机器人状态，重放后续，生成恢复数据（与 I5 共用）。
4. **重复（repeat）**：堆叠/整理数量从 N 增到 N+1，测组合长度泛化。
5. **换序（permute）**：独立技能换序（如先放 A 再放 B），测指令条件组合。

### 3.3 可行性过滤（拒绝率是核心监控指标）

- **运动学**：目标位姿 IK 可达，关节不超限。
- **碰撞**：Isaac Lab 快速检查（F14）。
- **可供性**：物体宽度/抓取轴/接近方向/所需间隙与源段匹配。
- **文法**：`post(s_k) ⊨ pre(s_{k+1})`。
- **进度**：重组后进度头单调，且至少命中一个官方得分点。

拒绝率过高说明分割或可供性阈值有问题；按任务族记录拒绝原因，作为 I8 的离线指标。

## 4. 关键产物 D：单模型技能令牌条件化（I12）

### 4.1 架构与损失

```python
def train_step(batch):
    z_true = batch.skill_token                 # 来自 I11 分割，软标签可选
    z_in = phase_dropout(z_true, p=PHASE_DROPOUT, model=self.model)
    feat = self.vlm(batch.obs)                 # 同一 backbone
    a_pred = self.action_expert(feat, z=z_in)  # FiLM / prefix token
    loss = flow_loss(a_pred, batch.action)
    loss += L1 * ce(self.skill_head(feat), z_true)
    loss += L2 * mse(self.progress_head(feat), batch.progress)
    loss += L3 * bce(self.boundary_head(feat), batch.boundary)
    return loss
```

- **相位 dropout**：以概率 p 把真值技能令牌替换为模型自预测或均匀分布，迫使动作头在相位不确定时仍能工作。这是对 I10 误判的训练期免疫。
- **软标签**：用分割信念/相邻段重叠度做标签平滑，避免硬 one-hot 过自信。
- **单模型**：三个头共享 backbone，一次前向；推理时中间件可读取这些头，不需要额外模型。

### 4.2 三档条件化的 A/B

| 档位 | 训练 | 推理 | 预期 |
|---|---|---|---|
| 硬条件 | 真值 one-hot | 中间件 one-hot | 最强但最脆 |
| 软条件 | 软标签 | 中间件信念嵌入 | 较稳，推荐默认 |
| 自预测 | 相位 dropout | 模型自预测 + 中间件门控 | 最省事，风险内藏 |

L0 用相位噪声注入（ε=0.05/0.1/0.2）比较三档的退化曲线；若软条件在 ε=0.2 下仍优于无相位基线，则保留 I12，否则降级为可选。

## 5. 关键产物 E：失败类型分解与预算分配

| 类型 | 定义 | 可观测信号 | 中间件可治？ | 归属 |
|---|---|---|---|---|
| A 感知/接近 | 从未接触目标 | 目标检测/EE 距离 | 否 | I1/I2/I9 |
| B 抓取/接触 | 接触但抓/插失败 | 夹爪闭合后物体未跟随 | 部分（I3） | I3/I5 |
| C 技能边界 | 抓取成功但抬/运/放失败 | 边界后进度停滞/物体掉落 | 是 | I10/I11 |
| D 长程停滞 | 无超时但进度平台 | 进度头平台+动作重复 | 是 | I10/I5 |
| E 超时 | 时间耗尽仍有进度 | 时间/得分点 | 是（保底） | I10/I4 |
| F 人为干扰 | 人介入后失败 | 手部检测/历史栈 | 是 | I4/I10 |

**预算分配规则**：先在单任务通道/离线日志上估计各类型的占比 \(p_A,\dots,p_F\)，再按「可治比例 × 每任务成功权重 1/320」排序。若 C+D+E+F 占比高，I10 优先；若 A+B 占比高，I1/I2/I3 优先。这样避免「中间件做了很多，但治的不是主要失败」。
