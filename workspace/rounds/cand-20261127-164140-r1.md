### 第 4 轮灵感驱动研究记录

**灵感词**：技能组合、手势识别

**直觉与动机**：

前几轮把 KEMPC 从「常识包容」推进到「证书驱动的分布式视觉伺服（CADVS）」，核心是让每一条控制决策都携带可验证的证据。本轮的两个灵感词看似分属两个领域——「技能组合」是机器人的行为组织问题，「手势识别」是人的意图表达问题——但它们其实指向同一个缺口：**证书体系目前只认证「单个动作是否安全」，还没有认证「多个动作拼起来是否仍然安全」，更没有认证「人让机器人拼的那个动作序列，是不是人真正想做的」。**

直觉上，手势是一种「人的技能组合语言」：人用手势说「先抓取、再抬升、再交给同伴」，本质上是在实时编写一段技能序列。技能组合则是机器的「语法」：它必须判断这段序列的前后置条件是否衔接、资源是否冲突、证书是否可传递。两者一对接，就出现一个非常自然的研究对象——**把人的手势序列编译成带证书的技能组合计划**。

但这里有一个不能含糊的地方：手势识别天然带语义歧义（同一手势在不同工位/不同操作员下含义不同，连续手势还会「协同发音」co-articulation），技能组合天然带组合爆炸与耦合。如果直接把「识别置信度高」当成「意图正确」，就会造出一个比前几轮更危险的失败模式：**证书链每一环都通过，但整条链服务的是错误的人类意图**。

**关键洞见**：证书不仅要「可验证」，还必须「可组合」。即需要一个证书代数（certificate algebra），使 h(σ1∘σ2) = h(σ1) ⊗ h(σ2)；同时手势必须被提升为一等证书源（Gesture Intent Certificate），其语义歧义集 A_ε 必须被显式携带、并在接地（grounding）阶段被消解，而不是被 top-1 置信度掩盖。换言之，**「识别置信度」是信号层证据，「意图证书」才是控制层证据，二者之间必须隔着一道可审计的接地与确认关卡**。

**严谨定义（本轮形式化目标）**：
1. 技能契约 σ = (π, Pre, Post, Inv, C, R, Δt)，其中 R 为资源足迹（关节、末端、传感器、工作空间、网络通道）；组合算子 ∘（顺序）、∥（并行）、⊕（选择）、^[k]（迭代）。
2. 证书代数 (Cert, ⊗, ∥, ⊒)：顺序证书取域交、裕度取 min 再减切换瞬态、窗口取 min 再减切换耗时；并行证书额外扣除干涉界 ι；⊒ 为精化偏序。
3. 手势意图证书 GRC = (ĝ, p_top, A_ε, t_recog, h_id, δ_sem)，准入规则 p_top > τ_g ∧ (γ(A_ε) 单点 ∨ 操作员确认) ∧ t_recog < τ_lat。
4. 接地函数 γ: G* → Plans，意图证书 IC = (plan, p_intent, assumptions, expiry)，p_intent = p_top · posterior(plan|context) · (1 − δ_sem)。
5. 组合证书闭包定理：若各技能证书成立且接口证书 IFace 成立，则组合证书成立，裕度按引理 32/33 衰减；组合搜索受证书裕度约束，不产生「空证书」计划。
6. GDSC = CADVS ∪ SCACA ∪ GICK ∪ CCCE ∪ GSGR ∪ SCRS，要求 Exec_GDSC ⊆ Exec_CADVS，且任何未通过闭包的组合都回退到最近一个已认证技能边界。

**本轮最大风险**：**意图接地鸿沟（intent grounding gap）**——手势识别可以在信号层以很高置信度正确，却在语义层被映射到错误的技能组合；此时所有证书都「合法」，系统会自信地执行一段完全合规但并非操作员本意的动作序列。证书能证明「怎么做是安全的」，却无法单独证明「做的是不是人想做的」。

## 2. 关键算法骨架

### IP-478 Skill Composition Algebra & Certificate Algebra (SCACA)

```python
@dataclass(frozen=True)
class Cert:
    domain: frozenset           # 有效状态域（谓词外延化）
    rho: float                  # 鲁棒裕度（>0 才可执行）
    window: float               # 时序有效窗口（s）
    kappa: float                # 置信度 ∈ (0,1]

@dataclass(frozen=True)
class SkillContract:
    sid: str
    pi: Callable[[State], Control]
    pre: Predicate
    post: Predicate
    inv: Predicate
    cert: Cert
    resources: frozenset[str]
    dt_min: float
    dt_max: float
    delta_switch: float = 0.05   # 切换瞬态扰动上界
    t_switch: float = 0.02       # 切换耗时

class SkillAlgebra:
    """技能组合算子；每个算子同时返回组合后的证书。"""

    def seq(self, a: SkillContract, b: SkillContract) -> SkillContract:
        iface = self.interface_cert(a, b)
        if not iface.ok:
            raise CompositionError(iface.reason)
        return SkillContract(
            sid=f'({a.sid};{b.sid})',
            pi=lambda x: self._run_seq(a, b, x),
            pre=a.pre,
            post=b.post,
            inv=and_(a.inv, b.inv),
            cert=self.cert_seq(a.cert, b.cert, iface),
            resources=a.resources | b.resources,     # 顺序可复用，但需时序独占
            dt_min=a.dt_min + b.dt_min,
            dt_max=a.dt_max + b.dt_max,
            delta_switch=max(a.delta_switch, b.delta_switch),
            t_switch=a.t_switch + b.t_switch,
        )

    def par(self, a: SkillContract, b: SkillContract) -> SkillContract:
        if a.resources & b.resources:
            raise CompositionError(f'resource conflict: {a.resources & b.resources}')
        iota = self.interference_bound(a, b)
        return SkillContract(
            sid=f'({a.sid}||{b.sid})',
            pi=lambda x: self._run_par(a, b, x),
            pre=and_(a.pre, b.pre),
            post=and_(a.post, b.post),
            inv=and_(a.inv, b.inv),
            cert=self.cert_par(a.cert, b.cert, iota),
            resources=a.resources | b.resources,
            dt_min=max(a.dt_min, b.dt_min),
            dt_max=max(a.dt_max, b.dt_max),
        )

    def cert_seq(self, ca: Cert, cb: Cert, iface: 'InterfaceCert') -> Cert:
        return Cert(
            domain=ca.domain & cb.domain,
            rho=min(ca.rho, cb.rho, iface.eps_pre) - self.delta_switch,
            window=min(ca.window, cb.window) - self.t_switch,
            kappa=ca.kappa * cb.kappa,      # 独立性假设，见 R34
        )

    def cert_par(self, ca: Cert, cb: Cert, iota: float) -> Cert:
        return Cert(
            domain=ca.domain & cb.domain,
            rho=min(ca.rho, cb.rho) - iota,
            window=min(ca.window, cb.window),
            kappa=ca.kappa * cb.kappa,
        )

    def refines(self, c: Cert, c2: Cert) -> bool:
        """⊒：c 精化 c2（c 更强）。"""
        return (c.domain >= c2.domain and c.rho >= c2.rho
                and c.window >= c2.window and c.kappa >= c2.kappa)
```

### IP-479 Gesture Intent Certificate Kernel (GICK)

```python
@dataclass(frozen=True)
class GestureRecognitionCert:
    g_hat: str
    p_top: float
    A_eps: frozenset[str]       # 语义歧义集，显式携带
    t_recog: float              # 识别端到端时延
    t_stamp: float
    h_id: str                   # 操作员 ID（用于个性化校准）
    delta_sem: float            # 语义校准误差（历史统计）

class GestureIntentCertificateKernel:
    def __init__(self, vocab, tau_g=0.85, eps_amb=0.10,
                 tau_lat=0.30, tau_stale=0.50):
        self.vocab, self.tau_g, self.eps_amb = vocab, tau_g, eps_amb
        self.tau_lat, self.tau_stale = tau_lat, tau_stale

    def recognize(self, frames, t_stamp) -> GestureRecognitionCert:
        probs = self.model(frames)                 # Δ(G)
        g_hat = max(probs, key=probs.get)
        p_top = probs[g_hat]
        A_eps = frozenset(g for g, p in probs.items()
                          if p >= p_top - self.eps_amb)
        return GestureRecognitionCert(
            g_hat=g_hat, p_top=p_top, A_eps=A_eps,
            t_recog=self.last_inference_latency,
            t_stamp=t_stamp, h_id=self.current_operator,
            delta_sem=self.calibration_error(self.current_operator))

    def admit(self, grc: GestureRecognitionCert, grounding, now) -> bool:
        """准入规则：信号置信 + 语义歧义消解 + 时序新鲜。"""
        if grc.p_top <= self.tau_g:
            return False
        if grc.t_recog > self.tau_lat:
            return False
        if now - grc.t_stamp > self.tau_stale:
            return False
        plans = {grounding.plan_of(g) for g in grc.A_eps}
        if len(plans) == 1:
            return True                          # 歧义在语义层等价
        return self.confirm_operator(grc.A_eps)  # 显式人机确认，不可默认通过

    def cert_payload(self, grc, admitted) -> dict:
        return {
            'cert_id': 'kc_gesture_intent',
            'payload': {'admitted': bool(admitted), 'g_hat': grc.g_hat,
                        'p_top': grc.p_top, 'ambiguity': sorted(grc.A_eps),
                        'delta_sem': grc.delta_sem, 'operator': grc.h_id},
            't_stamp': grc.t_stamp,
            'validity_window': self.tau_stale,
            'src_node': 'gesture',
        }
```

### IP-480 Compositional Certificate Closure Engine (CCCE)

```python
@dataclass(frozen=True)
class InterfaceCert:
    ok: bool
    eps_pre: float      # Post(a) ⇒ Pre(b) 的鲁棒裕度
    eps_res: bool       # 顺序组合的资源时序独占成立
    eps_time: bool      # a.dt_max + b.dt_max ≤ 截止时间
    reason: str = ''

class CompositionalCertificateClosureEngine:
    def close(self, plan: list[SkillContract]):
        """沿计划做证书闭包；任一步裕度/窗口耗尽即拒绝。"""
        if not plan:
            return None, ['empty plan']
        cert = plan[0].cert
        for a, b in zip(plan, plan[1:]):
            iface = self.interface_cert(a, b)
            if not iface.ok:
                return None, [f'{a.sid}->{b.sid}: {iface.reason}']
            cert = self.cert_seq(cert, b.cert, iface)
            if cert.rho <= 0:
                return None, [f'robustness exhausted at {b.sid}: rho={cert.rho:.3f}']
            if cert.window <= 0:
                return None, [f'validity window exhausted at {b.sid}']
        return cert, []

    def interface_cert(self, a, b) -> InterfaceCert:
        eps_pre = robustness_margin(a.post, b.pre)     # 模型/采样估计
        res_ok = self._time_exclusive(a, b)            # 顺序组合需时序独占
        time_ok = a.dt_max + b.dt_max <= self.deadline
        ok = eps_pre > self.eps_pre_min and res_ok and time_ok
        return InterfaceCert(ok, eps_pre, res_ok, time_ok,
                             '' if ok else 'interface cert failed')

    def _time_exclusive(self, a, b) -> bool:
        # 顺序组合：共享资源必须在切换后释放；由 SCRS 在运行时再次核验
        return a.resources & b.resources == frozenset() or \
               self._release_guaranteed(a, b)
```

### IP-481 Gesture-Skill Grounding Resolver (GSGR)

```python
@dataclass(frozen=True)
class IntentCert:
    plan: tuple[SkillContract, ...]
    p_intent: float
    assumptions: tuple[str, ...]
    expiry: float
    operator: str

class GestureSkillGroundingResolver:
    def __init__(self, gamma: dict[str, tuple[str, ...]], context: 'ContextModel'):
        self.gamma = gamma          # 手势 -> 技能序列模板（符号级）
        self.context = context
        self.library: dict[str, SkillContract] = {}

    def plan_of(self, gesture: str) -> tuple[str, ...]:
        return self.gamma.get(gesture, tuple())

    def resolve(self, grc: GestureRecognitionCert, ctx) -> IntentCert:
        # 1) 歧义集 → 候选计划集（去重）
        candidate_sids = {self.plan_of(g) for g in grc.A_eps}
        candidates = [tuple(self.library[s] for s in seq) for seq in candidate_sids]
        # 2) 上下文后验重加权（物体/工位/任务阶段）
        posterior = self.context.posterior(candidate_sids, ctx)
        # 3) 取后验最大者，并显式记录其依赖假设
        best_seq = max(posterior, key=posterior.get)
        plan = tuple(self.library[s] for s in best_seq)
        p_intent = grc.p_top * posterior[best_seq] * (1.0 - grc.delta_sem)
        return IntentCert(
            plan=plan, p_intent=p_intent,
            assumptions=self._assumptions(best_seq, ctx),
            expiry=grc.t_stamp + self.context.horizon,
            operator=grc.h_id)

    def _assumptions(self, seq, ctx) -> tuple[str, ...]:
        # 例：('object=graspable', 'station=A', 'no_human_in_workspace')
        return tuple(self.context.assumptions(seq, ctx))
```

### IP-482 Skill Composition Runtime Supervisor (SCRS)

```python
class SkillCompositionRuntimeSupervisor:
    def __init__(self, ccce: CompositionalCertificateClosureEngine,
                 tcvm, mrcc):
        self.ccce, self.tcvm, self.mrcc = ccce, tcvm, mrcc
        self.boundary = 0          # 最近一个已认证技能边界

    def step(self, ic: IntentCert, k: int, state: State, now: float):
        skill = ic.plan[k]
        # 1) 技能不变量
        if not skill.inv(state):
            return self._rollback(ic, k, 'invariant_violated')
        # 2) 证书时效（复用 TCVM 的证书年龄监控）
        if now > ic.expiry or not self.tcvm.cert_valid(skill.cert, now):
            return self._rollback(ic, k, 'cert_stale')
        # 3) 组合接口在运行时再次核验（静态证书的假设可能已被打破）
        if k + 1 < len(ic.plan):
            iface = self.ccce.interface_cert(skill, ic.plan[k + 1])
            if not iface.ok:
                return self._rollback(ic, k, iface.reason)
        else:
            self.boundary = k
        # 4) 执行；跨机一致性由 MRCC 决定是否降级
        if self.mrcc.status().fallback != FallbackAction.NONE:
            return self.mrcc.status().fallback
        return skill.pi(state)

    def _rollback(self, ic, k, reason):
        # 回退到最近已认证边界；若边界不可用则交还 CADVS 教师路径
        self.boundary = max(0, min(self.boundary, k - 1))
        return Rollback(target=self.boundary, reason=reason)
```

### GDSC 统一执行流（单步）

```python
def gdsc_step(state: State, frames, now: float) -> ControlOutput:
    """手势 → 意图证书 → 组合闭包 → 运行时监督；任一门失败即交还 CADVS。"""
    # 0) 手势识别（信号层，异步高频）
    grc = gick.recognize(frames, now)

    # 1) 意图准入：置信 + 歧义消解 + 新鲜度
    if not gick.admit(grc, gsgr, now):
        return ControlOutput(hold(state), path='gesture_hold',
                             reason='intent_not_admitted', certs=gick.cert_payload(grc, False))

    # 2) 语义接地：歧义集 → 计划 + 意图证书
    ic = gsgr.resolve(grc, context)
    if ic.p_intent < P_INTENT_MIN:
        return ControlOutput(hold(state), path='intent_low_conf',
                             reason=f'p_intent={ic.p_intent:.3f}')

    # 3) 组合证书闭包（静态）：任一接口/裕度失败即拒绝
    cert, errs = ccce.close(list(ic.plan))
    if cert is None or cert.rho <= 0:
        return fallback_to_cadvs(state, reason='composition_cert_fail', errors=errs)

    # 4) 运行时监督：逐技能不变量 + 时效 + 接口复验
    return scrs.step(ic, k=scrs.current_index(ic), state=state, now=now)
```

## 3. 复杂度分析（增量更新）

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 | 实时性指标 |
|---|---|---|---|---|

| **端到端（手势→首动作）** | **期望 < 40ms** | **O(F·d + |plan|)** | **P99 < 80ms** | **满足人机交互节拍** |
| **端到端（组合执行单步）** | **< 0.1ms 额外开销** | **O(1)** | **复用 CADVS** | **不劣化 v30** |

**通信开销**：GRC 约 300 bytes/条（含歧义集），IC 约 1-2 KB/条（含计划与假设），均走已有 DDS 证书链路；手势模型推理在独立进程，不阻塞 500Hz 控制环。

## 4. 正确性论证（增量更新）

### 引理 32（顺序组合的证书闭包）

**陈述**：设技能 σ1、σ2 的证书 C1=(D1,ρ1,Δt1,κ1)、C2=(D2,ρ2,Δt2,κ2) 成立，接口证书 IFace=(ε_pre, ε_res, ε_time) 成立。则顺序组合 σ1;σ2 在 D1∩D2 上保持 Inv1∧Inv2，并以鲁棒裕度 ρ12 ≥ min(ρ1,ρ2,ε_pre) − δ_switch 达成 Post2，有效窗口 Δt12 = min(Δt1,Δt2) − t_switch。

**证明**：由 C1，σ1 在 D1 上以裕度 ρ1 保持 Inv1 并达成 Post1。IFace 的 ε_pre 保证 Post1 ⇒ Pre2 在扰动不超过 ε_pre 时成立，故 σ2 可启动。由 C2，σ2 以裕度 ρ2 保持 Inv2 并达成 Post2。切换瞬间控制律由 π1 切至 π2，状态偏移有界 δ_switch（SCRS 在切换边界做不变量检查，越界即回滚），故组合裕度为三者最小值减切换瞬态。窗口按端到端耗时相加，取 min 后减 t_switch。归纳可得任意有限长计划。∎

**工程含义**：顺序组合不是「证书的简单拼接」，切换瞬态 δ_switch 与接口裕度 ε_pre 是两处最易被忽略的裕度税；CCCE 的 `rho<=0` 拒绝条件正是该引理的算法化。

### 引理 33（并行组合的干涉有界闭包）

**陈述**：设 σ1∥σ2 资源足迹不相交（R1∩R2=∅），且存在干涉界 ι 使两子系统的耦合状态增量满足 ‖Δx_cross‖ ≤ ι。则组合证书在 D1∩D2 上成立，鲁棒裕度 ρ∥ ≥ min(ρ1,ρ2) − ι。

**证明**：资源不相交保证执行器/传感器无直接竞争；剩余耦合仅通过共享环境状态。由小增益/扰动分析，若每个子系统的裕度大于耦合注入 ι，则各自仍保持不变量。故组合裕度至多损失 ι。ι 由离线系统辨识与在线残差监控给出上界。∎

**工程含义**：并行组合的安全性完全依赖 ι 的保守性；静态资源足迹无法覆盖「共享工作空间内的动态遮挡/气流/地面反力」等隐式耦合，故 SCRS 仍需运行时复验（见 R36）。

### 引理 34（手势意图证书的误意图风险界）

**陈述**：设 GRC 满足准入条件 p_top>τ_g、t_recog<τ_lat、now−t_stamp<τ_stale，且歧义集 A_ε 经接地后或为单计划、或经操作员确认（确认错误率 δ_confirm）。则执行计划偏离操作员真实意图的概率满足 r_intent ≤ (1−τ_g) + (1−p_top)·δ_sem + 1[γ(A_ε) 非单点]·δ_confirm。

**证明**：误意图事件可分解为三互斥来源：(i) top-1 本身错误，概率 ≤ 1−p_top ≤ 1−τ_g；(ii) top-1 正确但语义接地偏差，概率 ≤ p_top·δ_sem ≤ δ_sem；(iii) 歧义未在语义层消解且确认失败，概率 ≤ δ_confirm。三者取并集上界即得。∎

**诚实声明**：该界是**保守并集界**，且 δ_sem、δ_confirm 都依赖标定与操作员，实际值难以先验获得；更关键的是，它只界定了「单次手势」的误意图概率，**不覆盖连续手势序列的累积语义漂移**（co-articulation 会改变单个手势的边界与含义）。因此 GICK 的 `delta_sem` 必须按操作员在线更新，且 IC 必须带 expiry 强制重认证。

### 定理（GDSC 执行集收缩与意图认证执行）

**陈述**：在以下条件下：
(A1) 每个进入计划的技能均携带 CADVS 证书（十二证 + FQC/DLC），且 `ccce.close` 返回 ρ>0；
(A2) 手势意图证书通过 GICK 准入，IC.p_intent ≥ P_INTENT_MIN；
(A3) SCRS 在每个技能边界复验不变量、证书时效与接口；
则 Exec_GDSC ⊆ Exec_CADVS；且任一被执行的控制步，要么属于某个已闭包认证的组合计划，要么是回滚到已认证边界的动作或交还 CADVS 教师路径的动作。

**证明**：
- 包含性：GDSC 的执行入口只有两条——(i) `scrs.step` 返回已闭包计划的技能策略；(ii) 任一前置门失败时 `fallback_to_cadvs`/`hold`/`Rollback`。路径 (i) 的每个技能证书都继承自 CADVS，且组合闭包只在 ρ>0 时放行；路径 (ii) 均属于 CADVS 的教师/回退执行集。故 Exec_GDSC ⊆ Exec_CADVS。
- 意图认证：由引理 34，准入使 r_intent 有界；但该界只作用于「选择哪个计划」，不改变「计划内动作是否安全」——后者由引理 32/33 与 CADVS 证书保证。两类风险在证书链上**正交**，这正是「安全」与「合意」必须分开认证的原因。∎

**核心洞察**：本定理刻意**不**声称「Exec_GDSC 更安全」。它只声称执行集收缩且意图可审计。因为手势引入的是一类**新的、与物理安全正交的风险维度**（合意性），用物理证书去「证明」合意性在逻辑上是不成立的——这也是本轮最大风险的根源。

## 6. 本轮最大风险（最终确认）

**一句话**：**「意图接地鸿沟」是证书体系的结构性盲区**——手势识别可以在信号层以 0.95 的置信度正确、技能组合可以在物理层以正的鲁棒裕度全部闭包通过，但「这个手势在这个工位、这个操作员、这个任务阶段究竟意味着哪段技能序列」是一个**语义层问题，物理证书在原理上无法认证它**；系统于是会以完整的证据链自信地执行一段完全合规却并非人本意的动作，而操作员看到「全部证书通过」反而更容易放弃复核——这不是算法精度问题，而是**「安全认证」与「合意认证」被混为一谈的范畴错误**，也是 GDSC 从「可信执行」走向「可信协作」的生死线。
