## 第 8 轮（2026-10-25）：LITE-COMP——把“轻量、竞赛、柔顺”压进一个 30Hz 的接触回路

> 本轮是本次灵感循环的第 1 轮；文件沿第 7 轮 PILOT-GPR 继续，不推倒重来。检索/核验日期统一为 **2026-10-25（UTC）**。

### 0. 本轮结论

三句话：

1. **规则把优化目标钉死**：32 任务 × 10 次 = 320 次真机；先看 32 任务总平均成功率，成功率相同才看总平均步骤分，再相同看提交日期。上一轮把“步骤分约 60%”当成主目标需要降级——步骤分只是 tie-break；为部分分牺牲完整成功是负期望，但在成功率相同的情况下，步骤分和更早提交仍然值钱。
2. **公开榜仍是占位**：`leaderboard.html` 显示 Coming Soon；`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，8 个模型成功率 20.5–29.7、步骤分 28.1–39.0；`runs.html` 仍是 256/256 占位。没有真实“榜首”可拆，不能把“榜首 <30%”当事实。能拆的是占位模型 archetype 与文献瓶颈：最后几毫米接触、长程提前停、撤销式干扰、延迟抖动、单模型约束。它们共同指向“慢语义 + 快接触回路”，而不是再大一号的 VLA。
3. **三个灵感词分别落地**：轻量化设计 → **LDS** 双频栈 + 可选 0.8B 蒸馏；机器人竞赛 → **SFX** 成功闸门/时间预算/任务组合/早提交；柔顺控制 → **TCP** 任务柔顺剖面 + **CGP** 接触门控原语。合起来是 **LITE-COMP**：一个模型、两条时间尺度、三类接触行为、四道成功闸门。

一句话：**用 30Hz 的轻量接触回路，把慢 VLA 从“最后几毫米”里救出来；用成功率优先的竞赛策略，把有限调试预算押到最能抬高平均成功率的短板上。**

### 2. 已核实事实

#### 2.1 规则与评分

| 项目 | 官方/可核实内容（2026-10-25） | 对方案的含义 |
|---|---|---|
| 赛道 | 通才模型赛道；一个模型完成全部 32 任务；不得混合多个模型 | 不能做“按任务切模型”的 ensemble；反射头必须是同一 checkpoint 的一个头，或确定性控制器 |

| 观测 | 4 路 RGB、双臂关节/EE 位姿、夹爪、language；可选 `obs_delta_indices`、`image_resize`、`action_chunk_size` | 轻量栈可控制输入分辨率和 chunk，降低延迟 |

#### 2.2 排行榜与“头部方案”

- `leaderboard.html` 仍是 Coming Soon；`leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`；`runs.html` 仍是 256/256 占位。
- 因此：**没有任何真实头部队伍的成功率、步骤分、延迟、模型规模可分析**。公开可见的 GigaBrain-0、DM0、DreamZero、π0.5、WALL-OSS、MolmoAct2 等只是占位名字/架构线索，不是排名证据。
- 可以做的是“archetype 拆解”：大 VLA、世界模型、双系统、轻量 VLA 四类，分别在最可能失败的环节上打靶。第 7 轮已做了一部分；本轮把它收敛成“最后几毫米 + 长程 + 干扰 + 延迟”四条。

#### 2.3 硬件与 API

- Dex1-1：550g、90mm 行程、5–120N 可调夹持力、0.1mm 分辨率、1000Hz 控制；内部支持力矩/刚度/阻尼。
- **比赛 API 不暴露力/力矩/刚度命令**，只给开度目标；夹爪内部仍有力限，但选手不能直接编程“柔顺系数”。
- 结论：柔顺控制必须写成“位置目标整形 + 部分闭合 + 接触后驻留/回退/搜索 + 释放轨迹”的行为柔顺，而不是“调用阻抗控制器”。

#### 2.4 数据

- 32 个 HF 数据集，约 33k episodes / 169h / 30fps / 480×640；四路相机：`head_stereo_left/right`、`wrist_left/right`。
- EE 位姿有 base/torso 两套；Dex1 夹爪范围 5.5–0.0（open→close）。
- 每个任务有 5 条英文复述；`info.json` 有 `unseen_object_3`、`human_1`、`human_4` 等泛化备注。
- 演示平均时长 6.2s（HangCup）–37.6s（ToolboxStorage），中位 16.4s，均值 18.4s。180s 对短任务是“多次尝试”的预算，对长任务是“少犯错”的预算。

#### 2.6 文献给的可落地证据

- **SmolVLA**：450M，10× 更小，异步推理 + action chunk，仍具竞争力 → 轻量学生不是玩具。
- **TinyVLA**：小模型 + 高效多模态，说明“数据/接口”比参数量更关键。
- **世界模型蒸馏**：0.8B 学生、32ms、1.86GB（RTX5090）、RoboCasa-GR1 50.5、LIBERO 97.9；教师只在离线对齐特征 → **WMD 可作为 Tier B，不把世界模型搬进运行时**。
- **TIDAL**：低频宏意图缓存 + 高频单步 flow，动态任务 2.5× → 双频不是“两个模型”，而是同一模型的不同时间尺度。
- **A2C2**：轻量 action-chunk 修正头，不重训基座，延迟下 +23%/+7% → **LDS 的反射头可以直接借鉴**。
- **VFAL / peg-in-hole**：视觉反馈 + 柔顺/搜索，显著提高插入成功率 → **CGP 的搜索/座合原语**。
- **VLCP**：失败抓取 27.3% 在 episode 内恢复；**Restore, Don't Retry**：恢复优于重试 → **SFX 的恢复优先于重跑**。
- **Self-Adaptive VLA / 事件触发异步**：延迟/硬件偏移下仍能保持成功率 → 服务层与反射层是比赛差异点。

### 3. 三个灵感词怎么锚定，而不是贴标签

#### 3.1 轻量化设计 → LDS（Lightweight Dual-rate Stack）

- **不是“把模型压小”**，而是把控制回路拆成两个时间尺度：
  - 慢回路：6B/3B VLA，5–10Hz，出语义子目标 + 粗动作 chunk；
  - 快回路：30–50Hz 轻量反射头/确定性控制器，处理接触、对齐、释放、回退。
- 轻量化的三个预算：
  1. **算力预算**：4 路 RGB + 语言 + 状态，分辨率/帧率可调；chunk 不是越大越好。
  2. **延迟预算**：p99 比 p50 更重要；异步提交 + 缓存 + 反射头覆盖基座抖动。
  3. **动作预算**：运输用大 chunk/快走，接触用小步/慢走；不是全程慢。
- 可选 **WMD**：把世界模型当离线教师，蒸馏 0.8B 学生；如果 Tier A 的 6B + 反射已经够快，不做蒸馏，避免“为了轻量而轻量”。

#### 3.2 机器人竞赛 → SFX（Success-First eXecution）

- **成功闸门**：每个子目标前检查“抓稳了吗/目标可见吗/对齐误差够小吗/时间够吗”；不满足就重观测/重定位，不硬着头皮执行。
- **恢复优先于重试**：检测到“已完成子目标被撤销”（人手拿走、拉链被拉开、盖子被拧回）时，只修复被撤销的部分，不从头重跑。
- **时间预算**：`T_left` 减去“剩余步骤的保守估计 + 验证开销”；长任务保留恢复预算，短任务允许更多尝试。
- **任务组合**：按“提升总平均成功率的边际收益/成本”排序；先消灭 0% 任务，再攻高杠杆短板；不要平均用力。
- **方差意识**：10 次/任务的单任务成功率标准误约 14.5pp；320 次总体的标准误约 2.6pp（p≈0.3）。单次调试槽不能证明 +10pp；用机制指标/配对设计/多槽重复。
- **早提交**：排名第三键是提交日期；先交一个“能跑、无崩溃、覆盖全部任务”的基线，再迭代。不要为了最后一个点子错过截止。

#### 3.3 柔顺控制 → TCP + CGP

- **TCP（Task-specific Compliance Profile）**：从演示里挖每个任务的接触相位，形成剖面：
  - 接近速度、接触前减速距离；
  - 接触后驻留时长；
  - 夹爪闭合量/部分闭合策略；
  - 释放速度/释放前驻留；
  - 失败后的回退距离、搜索半径、重试次数。
- **CGP（Contact-Gated Primitives）**：把“最后几毫米”写成确定性原语：
  - `align`：视觉/位姿对齐到容差；
  - `approach`：按 TCP 速度接近；
  - `spiral/search`：小半径搜索，遇到接触即停；
  - `seat`：低速压入/座合，检测到位；
  - `release`：按 TCP 释放，不甩、不拖；
  - `settle`：放置后短暂驻留，等物理稳定；
  - `recover`：回退、重观测、重试/修复。
- **为什么是行为柔顺**：API 只给位置；但“慢、停、部分闭合、回退、搜索、释放”都能用位置目标实现，且可解释、可调试、可复现。
- **单模型合规**：反射头优先做成同一 checkpoint 的辅助头（训练时多任务损失），或纯确定性控制器；不做“第二个模型”。

### 4. 竞争格局：没有真榜首，只有可打的瓶颈

| 可能的强基线 archetype | 强项 | 最可能瓶颈 | LITE-COMP 的回应 |
|---|---|---|---|
| 大 VLA（π0.5/GR00T/WLA 类） | 语义泛化、语言跟随、数据规模 | 接触最后几毫米；延迟高；长程提前停 | LDS 快回路 + TCP/CGP |
| 世界模型（DreamZero/GigaBrain 类） | 物理预测、长程规划 | 运行时重；实时性；真机接触误差 | WMD 只做离线教师；SFX 兜底 |
| 双系统（快慢分层） | 快反应 + 慢推理 | 接口/切换抖动；快系统能力有限 | LDS 的反射头 + 接触门控，接口更窄 |
| 轻量 VLA（SmolVLA/TinyVLA 类） | 低延迟、易部署 | 语义/长程弱；接触精度不足 | 保留 6B 基座，轻量只做反射；可选蒸馏 |

**头部方案拆解协议**（等真实榜单出来再用，不现在编）：
1. 先看 `generated_from` 是否还是 `gen_leaderboard.py`；是则停止排名分析。
2. 拉 `leaderboard_data.json`，按任务/轴拆成功率；看是否有人用“单轴满分”换总平均。
3. 看 `runs.html` 视频，按“抓取/对齐/插入/释放/验证”标失败点；统计最后一步失败占比。
4. 看是否披露模型规模、控制频率、延迟；对比“大模型慢”与“小模型弱”的取舍。
5. 复现其公开代码/配置；不复现就不把论文数字当基线。

### 5. 主判断与方案

**主判断**：在位置-only API、单模型、320 次真机的约束下，边际收益最高的不是“更大的 VLA”，而是：

1. **把慢 VLA 的最后几毫米交给快回路**（LDS）；
2. **把演示里的接触习惯变成任务剖面**（TCP）；
3. **把接触写成可验证的确定性原语**（CGP）；
4. **把竞赛策略写成成功闸门/恢复/预算/组合**（SFX）；
5. **可选地把世界模型蒸馏成 0.8B 学生**（WMD），但绝不把世界模型搬进在线回路。

**LITE-COMP 组件表**：

| 组件 | 一句话 | 运行时 | 优先级 |
|---|---|---|---|
| LDS | 慢 VLA + 30Hz 反射/确定性快回路 | 是 | P0 |
| TCP | 每任务接触剖面（速度/驻留/闭合/释放） | 是（查表） | P0 |
| CGP | align/approach/search/seat/release/settle/recover | 是 | P0 |
| SFX | 成功闸门、恢复、时间预算、任务组合 | 是 | P0 |
| WMD | 世界模型离线教师 → 0.8B 学生 | 否（训练） | P2 |
| SSG/PGL/OPT/ICR/NRB | 第 7 轮的语义/位姿/组合/恢复组件 | 部分 | P1 |

**四个可证伪假设**：

- **H1**：在 6–8 个紧配合任务上，TCP + CGP 相对“全局慢速”提高 ≥10pp 成功率，且不增加超时率。
- **H2**：LDS 把接触阶段的 p99 反应延迟降到 <50ms，在人为干扰轴提高 ≥5pp。
- **H3**：SFX 的“恢复优先于重试”减少长任务的平均完成时间，且不降低成功率。
- **H4**：WMD 的 0.8B 学生在至少 24/32 任务上不低于 6B 教师 5pp，吞吐 ≥2×；否则不做蒸馏。

### 6. 与第 7 轮的关系：保留、升级、降级、杀掉

第 6 轮 FLEET 的 6.0 不是技术全错，而是“工程检查单当研究主线 + 步骤分目标错位”；本轮不再重复，把 FLEET 降级为部署检查表，把主叙事让给 LDS/TCP/CGP/SFX。

| 第 7 轮内容 | 本轮处理 | 理由 |
|---|---|---|
| WLA-1.0 基座、SSG 语义子目标、PGL 位姿图、OPT 物体中心、ICR 指令重述、NRB 人类脚本 | **保留** | 仍是语义/泛化/干扰的基础设施 |
| GPR-VLA（世界模型 + 策略） | **升级为 WMD** | 世界模型只做离线教师；在线只留学生/反射，避免运行时重 |
| ACP-GF（异步 chunk） | **升级为 LDS** | 从“异步”扩展到“双频 + 反射头 + 接触门控” |
| TLE（长程） | **并入 SFX** | 长程的核心是成功闸门/恢复/预算，不是单独的规划器 |
| FLEET 工程检查单 | **降级为部署检查表** | 它是“防归零”，不是研究创新；保留但不占主叙事 |
| 步骤分优先 | **降级为 tie-break** | 官方排序成功率先行；为部分分牺牲成功是负期望 |
| 全物理世界模型在线 | **杀掉** | 实时性/真机误差/单模型约束都不划算 |
| 多模型 ensemble/按任务切模型 | **杀掉** | 违反单模型规则；部署也复杂 |
| 任务硬编码坐标/轨迹 | **杀掉** | 规则风险 + 泛化差；用学习/在线估计 |
| 电池/续航猜测 | **杀掉** | 无官方数据；把“续航”改为服务稳定性/热/内存 |

**对第 7 轮“步骤分约 60%”的修正**：如果评分表里步骤分的权重看起来高，那只是“单次运行的分数构成”，不是“排名的目标函数”。排名先比成功率；一个 2/3 步的成功，永远排在 3/3 步的成功之后，但一个 2/3 步的失败不会因为步骤分高而变成成功。正确策略是：**在保证成功的前提下再优化步骤分/时间；不要为了多拿一步而增加失败概率。**

### 7. 风险与反证

| 风险 | 现实 | 缓解 |
|---|---|---|
| 单模型规则不允许独立反射模型 | 规则只写“不得混合多个模型”，未写“同一 checkpoint 多频率执行” | 反射头做成同一 checkpoint 的辅助头；或纯确定性控制器；模型卡披露 |
| API 只有位置，柔顺做不出来 | 不能命令力/刚度，但能做慢速/驻留/部分闭合/回退/搜索 | TCP/CGP 全部用位置目标实现；不宣称力控 |
| 演示统计有选择偏差 | 只看了首个分片；没有成功标签 | 扩大到全部 32 任务/多分片；用成功/失败配对验证 |
| 延迟改善不等于成功率 | 快回路可能引入抖动/过拟合 | 先离线回放，再单任务调试槽 A/B；p99 与成功率一起看 |
| 真实榜首不可见 | 占位榜不能证明“榜首 <30%” | 不把占位数当基线；用文献瓶颈 + 自有基线；等真实榜单 |
| 10 次调试槽统计功效不足 | 单任务 SE≈14.5pp | 机制指标（接触驻留/插入深度/释放速度）+ 配对设计 + 多槽重复 |
| WMD 蒸馏掉点 | 0.8B 学生可能在某些任务掉 >5pp | 先做 Tier A；学生只在 24/32 任务不掉 5pp 时上线 |
| 时间不够 | 8 周要覆盖 32 任务 | P0 只做 6–8 个高杠杆任务；其余用基座 + 通用原语；先交基线 |

### 8. 本轮不做什么

- 不做在线世界模型/全物理仿真；不做多模型 ensemble；不按任务切模型；不硬编码任务坐标。
- 不宣称“力控/阻抗控制”；API 没有力/刚度命令。
- 不把占位榜的分数当真实排名；不把“榜首 <30%”写成事实。
- 不为了步骤分牺牲成功率；不把 10 次调试槽的 +1 次成功当 +10pp 证据。
- 不猜电池化学/续航；只做服务稳定性、热、内存、N 端口 soak。

### 9. 一句话押注

**在位置-only、单模型、320 次真机的约束下，把 6B VLA 的“最后几毫米”交给 30Hz 的轻量接触回路（LDS + TCP + CGP），用成功率优先的竞赛策略（SFX）分配时间/重试/调试预算；世界模型只做离线教师，不进运行时。**

## 第 8 轮产物：LITE-COMP——单模型、双频接触回路与成功率优先的竞赛执行手册

> 本产物是工程方案与研究计划，不是已实现结果。所有“已核实”事实标注来源；所有“预计/假设”明确标注，不与事实混写。检索/核验日期：**2026-10-25（UTC）**。

### A. 摘要

**LITE-COMP** 由四个 P0 组件与一个 P2 可选项组成：

| 组件 | 全称 | 解决什么 | 运行时 |
|---|---|---|---|
| **LDS** | Lightweight Dual-rate Stack | 慢 VLA 的语义能力 + 30–50Hz 轻量回路的接触反应 | 是 |
| **TCP** | Task-specific Compliance Profile | 不同任务的接近速度、低速驻留、闭合量、释放速度 | 是（查表/学习选择） |
| **CGP** | Contact-Gated Primitives | 最后几毫米的 align/approach/search/seat/release/settle/recover | 是 |
| **SFX** | Success-First eXecution | 成功闸门、恢复优先、时间预算、任务组合、方差意识、早提交 | 是 |
| **WMD** | World-Model Distillation | 世界模型只做离线教师，蒸馏 0.8B 学生；不把世界模型搬进在线回路 | 否（训练） |

**核心判断**：在位置-only API、单模型、32 任务 × 10 次真机的约束下，边际收益最高的不是“再大一号的 VLA”，而是：

1. 把慢 VLA 的**最后几毫米**交给快回路（LDS）；
2. 把演示里的**接触习惯**变成任务剖面（TCP）；
3. 把接触写成**可验证的确定性原语**（CGP）；
4. 把竞赛策略写成**成功闸门/恢复/预算/组合**（SFX）；
5. 可选地把世界模型**蒸馏**成 0.8B 学生（WMD），但绝不把世界模型搬进在线回路。

**目标**：相对“同一基座 + 朴素 action chunk”的自有基线，整体成功率 +8–12pp；其中紧配合任务 +10–15pp，人为干扰轴 +5–10pp。**这不是对占位榜的承诺**，真实基线要等官方榜/自有真机调试。

**不做**：在线世界模型、多模型 ensemble、按任务切模型、任务硬编码坐标、无力控 API 却宣称力控、为步骤分牺牲成功率、把占位榜当真实排名。

#### B.2 评分数学

设任务 \(i\) 的第 \(r\) 次运行成功指示为 \(s_{i,r}\in\{0,1\}\)，步骤分为 \(q_{i,r}\in[0,1]\)，则：

\[
S=\frac{1}{32}\sum_{i=1}^{32}\frac{1}{10}\sum_{r=1}^{10}s_{i,r},
\qquad
Q=\frac{1}{32}\sum_{i=1}^{32}\frac{1}{10}\sum_{r=1}^{10}q_{i,r}.
\]

排名先比 \(S\)，再比 \(Q\)，再比提交时间。**不要**把 \(Q\) 当成主目标；但在 \(S\) 相同的边界上，\(Q\) 和早提交是真实的排序键。

#### B.3 方差与统计功效

二项分布的标准误：

\[
\mathrm{SE}(p)=\sqrt{\frac{p(1-p)}{n}}.
\]

| 场景 | n | p | SE | 95% CI 半宽 |
|---|---:|---:|---:|---:|
| 单任务 10 次 | 10 | 0.3 | 14.5pp | ±28.4pp |
| 总体 320 次 | 320 | 0.3 | 2.6pp | ±5.0pp |
| 单任务 10 次 | 10 | 0.5 | 15.8pp | ±31.0pp |
| 总体 320 次 | 320 | 0.5 | 2.8pp | ±5.5pp |

要在 80% 功效、双侧 \(\alpha=0.05\) 下检测 +10pp（从 0.3 到 0.4），每组约需：

\[
n\approx \frac{2(1.96+0.84)^2\,p(1-p)}{\Delta^2}
\approx \frac{15.7\times0.21}{0.01}\approx 330.
\]

**结论**：单个 10 次调试槽无法可靠证明 +10pp。必须用：

1. **机制指标**：接触驻留、插入深度、释放速度、time-to-contact、恢复次数；
2. **配对设计**：同一任务/同一扰动下 A/B，比较配对差；
3. **多槽重复**：至少 2–3 个调试槽，或 30–50 次自定义调试（若规则允许）；
4. **任务级 bootstrap**：按任务/轴重采样，报告 95% CI，不只看总平均。

#### B.4 时间预算

单次 180s。设当前已用 \(t\)，剩余步骤集合为 \(R\)，每步保守估计 \(E[T_j]\)，验证/恢复预留 \(T_{\mathrm{reserve}}\)：

\[
T_{\mathrm{left}}=180-t,\qquad
\text{可继续}\iff T_{\mathrm{left}}>\sum_{j\in R}E[T_j]+T_{\mathrm{reserve}}.
\]

- 短任务（HangCup 6.2s、StackBowls 10.1s）：允许 3–5 次重试；但不要把 180s 花在同一个错抓上。
- 长任务（ToolboxStorage 37.6s、StorePaddle 34.1s）：每步预算 + 恢复预算；宁可少做可选项，也不要超时。
- 接触驻留 0.2–0.5s 很便宜；一次盲目重跑 10–30s 很贵。**驻留比重跑便宜**。

#### B.5 单模型合规

规则只写“不得混合多个模型”，没有写“同一 checkpoint 不能多频率执行”。保守做法：

- **方案 A（推荐）**：同一 checkpoint，共享视觉/语言主干，加一个轻量反射头（<10M 参数），联合训练；服务时一个进程、一个权重文件。
- **方案 B（最稳）**：反射完全确定性（无学习权重）；不引入第二个模型。
- **方案 C（可选）**：蒸馏学生 + 反射头，仍是一个 checkpoint；教师只在训练时用。
- **禁止**：按任务加载不同权重、在线 ensemble、调用外部 API 模型、把任务 ID 映射到专用策略。
- **模型卡**：写明基座、反射头、训练数据、频率、许可证、外部依赖、单模型边界。

### D. 演示数据：接触剖面

#### D.1 方法

- **PlugCharger**：读取首个 parquet 分片（269 episodes / 1,022），用左右 EE 在 `gripper_base` 坐标系下的相对距离 \(d_t=\|p^L_t-p^R_t\|\) 作为“插头-插座接近”的代理；相对速度 \(v_t=\|(p^L_{t+1}-p^L_t)-(p^R_{t+1}-p^R_t)\|\times30\)。
- **StackBowls**：读取首个分片（412 episodes / 800），用夹爪状态 `<1 → >3` 且在 0.2s 内完成作为“释放”事件；去重后 754 次（406/412 episodes），未去重 1,168 次。
- **低速驻留**：包含最近点/释放点的连续低速段（\(v<0.03\) m/s）时长；这是“停一下”的代理，不是力/接触传感器。
- **注意**：没有成功标签；只用一个分片；相对 EE 距离不是物体距离。所有统计是描述性的，不是因果。

#### D.2 结果

| 指标 | PlugCharger（紧配合） | StackBowls（容错放置） |
|---|---:|---:|
| 分析样本 | 269 eps / 1,022 | 412 eps / 800 |
| 最近距离中位 | 0.152 m | — |
| 接触/释放速度中位 | 0.020 m/s | 0.071 m/s |
| 速度 <0.03 m/s 占比 | 62.5% | 17.2% |
| 低速驻留中位 | 0.23 s | 0.00 s |
| 低速驻留 ≥0.13s | 62.8% | 0.0% |
| 低速驻留 ≥0.3s | 42.0% | 0.0% |
| 接近速度中位 | 0.037 m/s；61.3% <0.05 | — |

#### D.3 解释

- **紧配合**：最后几毫米明显“慢 + 停”。这不是因为机器人“喜欢慢”，而是因为位置误差/视觉误差需要在线修正；停一下让夹爪/物体稳定，再座合。
- **容错放置**：更接近“边走边放”；释放速度中位 0.071 m/s，只有 17.2% <0.03；释放前几乎没有驻留。
- **对 TCP 的含义**：不要全局降速。紧任务用“慢接近 + 驻留 + 低速座合”；容任务用“中等速度 + 释放 + settle”。全局降速会拖长长任务、增加超时，且对容错任务没有收益。
- **对 CGP 的含义**：接触检测不能只看“距离最小”；要看速度骤降、夹爪开度停变、视觉 flow 降低。紧任务的“停”是可检测的。

| 参数 | 紧配合（PlugCharger/Ethernet） | 容错放置（StackBowls/Cups） | 拉链/软物体 | 长程 |

### E. 竞争格局与“头部方案”拆解

#### E.1 先确认：现在没有真实头部

#### E.2 四类强基线 archetype

| Archetype | 代表 | 强项 | 最可能瓶颈 | 我们的回应 |
|---|---|---|---|---|
| 大 VLA | π0.5、GR00T、WLA、GigaBrain | 语义泛化、语言跟随、数据规模 | 接触最后几毫米；延迟；长程提前停 | LDS + TCP + CGP |
| 世界模型 | DreamZero、GigaBrain、WLA 世界模型分支 | 物理预测、长程规划 | 运行时重；真机误差；实时性 | WMD 只做离线教师；SFX 兜底 |
| 双系统 | 快慢分层、System 1/2 | 快反应 + 慢推理 | 接口/切换抖动；快系统能力有限 | LDS 的窄接口反射 + 接触门控 |
| 轻量 VLA | SmolVLA、TinyVLA | 低延迟、易部署 | 语义/长程弱；接触精度不足 | 6B 基座 + 轻量反射；可选蒸馏 |

#### E.3 最可能的五个瓶颈

| 瓶颈 | 证据 | 影响 | LITE-COMP 的回应 |
|---|---|---|---|
| 最后几毫米接触 | 演示里紧任务低速驻留；peg-in-hole 文献；位置-only API | 紧任务整段失败；步骤分也拿不到 | TCP + CGP + 接触检测 |
| 长程提前停/漏步 | 4–5 检查点任务；VLCP 27.3% 恢复；长任务 37.6s | 前面全对，最后一步失败 | SFX 成功闸门 + 恢复 |
| 撤销式人为干扰 | `human_1/human_4` 备注；VLCP/Restore 文献 | 已完成子目标被撤销，重跑浪费 | 恢复优先于重试；只修复被撤销部分 |
| 延迟/抖动/N 端口 | 异步推理文献；A2C2 延迟实验；服务端要求 | 接触时动作过期；p99 抖动 | LDS 异步 + 反射；p99 监控 |
| 单模型 vs 专精 | 规则禁止混合模型；32 任务差异大 | 不能按任务切模型；大模型慢、小模型弱 | 一个基座 + 任务剖面/原语，不切模型 |

#### E.4 真实榜单拆解协议（等榜单出来再用）

1. **验真**：看 `generated_from` 是否还是 `gen_leaderboard.py`；是则停止排名分析。
2. **拆轴**：拉 `leaderboard_data.json`，按任务/泛化轴拆成功率；找“单轴满分/单轴零分”的模型。
3. **看视频**：`runs.html` 的 runs；按“抓取/对齐/插入/释放/验证”标失败点；统计最后一步失败占比。
4. **看延迟/规模**：是否披露模型大小、控制频率、p50/p99；对比“大模型慢”与“小模型弱”。
5. **复现**：公开代码/配置；不复现就不把论文数字当基线。
6. **更新先验**：把真实 per-task 成功率写回任务组合；重新算边际收益。

#### E.5 强基线“大概率怎么做”（假设，不是事实）

- 大 VLA + 多视角 + action chunk + 5 条语言复述 + 大规模演示/外部数据；语义轴强。
- 接触阶段靠“慢速 + 重试”，但没有显式接触剖面；紧任务成功率低。
- 人为干扰靠“从头重跑”，没有撤销检测；长任务掉分。
- 服务端用单进程/同步推理；N 端口下 p99 抖动；接触时动作过期。
- 单模型约束下不敢做专精；要么全用大模型（慢），要么全用小模型（弱）。

**我们的差异**：不跟它们比“更大”，比“最后几毫米更快、更稳、更可验证”；不跟它们比“更多模型”，比“一个模型内的双频”；不跟它们比“更多任务”，比“任务组合的边际收益”。

#### E.6 什么会让我们改变判断

- 真实榜单显示头部 >60%，且紧任务不是瓶颈 → TCP/CGP 的边际收益下降，转向语义/长程。
- 官方开放力/刚度 API → 行为柔顺可以升级为真正的阻抗/力控。
- 规则明确禁止同一 checkpoint 多频率执行 → LDS 退化为“异步 chunk + 确定性原语”，不做学习反射头。
- 演示统计在全部 32 任务/多分片上不成立 → TCP 的先验要重估。
- 单模型/外部数据限制导致 6B 基座不可用 → 直接走 0.8B 学生 + 反射头（WMD 提前）。

### F. LITE-COMP 架构

#### F.1 数据流

```text
language + 4×RGB + proprioception
        │
        ├── slow loop (5–10 Hz)
        │     VLA / WLA backbone
        │       ├── subgoal + step predicate (SSG)
        │       ├── coarse action chunk (8–16 steps)
        │       └── confidence / progress
        │
        ├── fast loop (30–50 Hz)
        │     reflex head / deterministic controller
        │       ├── residual pose correction
        │       ├── gripper open/close
        │       └── contact gate
        │
        ├── TCP table / profile selector
        │     (language + vision embedding → profile)
        │
        └── SFX governor
              gates / recovery / time budget / portfolio
                    │
                    ▼
        position targets + gripper + pivot (API)
```

#### F.2 组件职责

| 层 | 输入 | 输出 | 频率 | 失败时的退路 |
|---|---|---|---|---|
| 慢 VLA | 4 RGB、语言、状态 | 子目标、粗 chunk、置信度 | 5–10Hz | 保持上一 chunk；快回路接管 |
| 反射头 | 腕部/头部特征、EE 误差、夹爪、TCP | Δpose、夹爪增量、门控 | 30–50Hz | 确定性 P 控制/保持 |
| TCP | 语言/视觉 embedding、任务阶段 | 速度/驻留/闭合/释放参数 | 每阶段 | 全局保守剖面 |
| CGP | 目标位姿、接触信号、TCP | 原语动作/完成谓词 | 30–50Hz | 回退/重观测 |
| SFX | 进度、时间、置信度、失败类型 | continue/retry/restore/abort | 每步/每事件 | 安全 abort + 保留步骤分 |

#### F.3 运行时主循环

```python
class LiteCompPolicy:
    def __init__(self, base, reflex, tcp, sfx):
        self.base = base
        self.reflex = reflex
        self.tcp = tcp
        self.sfx = sfx
        self.chunk = None
        self.future = None
        self.step = None

    def reset(self, instruction, obs):
        self.step = self.sfx.first_step(instruction, obs)
        self.tcp.select(instruction, obs)
        self.chunk = None
        self.future = None

    def act(self, obs):
        if self.future is None or self.future.done():
            self.future = self.base.submit(obs, self.step)
        if self.future.done():
            out = self.future.result()
            self.chunk = out.chunk
            self.step = self.sfx.update_step(self.step, out, obs)
            self.future = None

        action = self.reflex.step(obs, self.chunk, self.tcp, self.step)
        action = self.sfx.gate(action, obs, self.chunk, self.step)
        return action
```

关键点：

- `submit` 非阻塞；`act` 不被基座推理阻塞。
- `chunk` 允许过期，但快回路用最新 `obs` 修正；过期超过阈值就保持/减速。
- `SFX.gate` 可以在接触前/后改变动作（例如强制驻留、禁止继续）。
- 每个 API step 都返回合法动作，不抛异常；异常在内部降级。

#### F.4 单模型合规

- **共享主干**：慢 VLA 与反射头共享视觉编码器；反射头只加 2–4 层 MLP/GRU，输出残差。
- **联合训练**：`L = L_action + λ1 L_reflex + λ2 L_gate + λ3 L_progress`；反射头可以用演示 + 扰动 + 延迟增强训练。
- **一个进程/一个权重**：服务端只加载一个 checkpoint；反射头是其中一部分。
- **模型卡**：写明“同一 checkpoint 的辅助头，不参与任务选择；无任务 ID 分支；无外部模型调用”。
- **若规则更严**：反射头退化为确定性控制器（P/PD + 状态机），仍然满足“一个模型”的字面要求。

#### F.5 部署

- 每个端口一个轻量服务进程；共享 GPU 上的基座（或每个进程一个副本，按显存决定）。
- 启动时 warmup 10–20 次；记录 p50/p95/p99；健康检查 `/health`。
- 观测：`obs_delta_indices` 只取需要的帧；`image_resize` 降到 256/320；chunk 8–16。
- 动作：EE 还是 joint 二选一；EE 更容易做残差修正，joint 更容易保安全；离线各测一次。
- 日志：每步时间戳、推理耗时、chunk 年龄、门控状态、失败类型；用于赛后复盘。
- 安全：动作限幅、速度限幅、工作空间边界、急停；人手进入时降速/暂停。
- N 端口 soak：4 小时连续跑，观察内存/热/延迟漂移；不要只测单次。

### G. LDS：轻量双频栈

#### G.1 为什么是双频

- 基座 VLA 的语义推理通常 5–10Hz；接触修正需要 30–50Hz。用 30Hz 的 API 调用频率去等 100–200ms 的基座推理，动作必然过期。
- 异步 chunk 能缓解，但不能解决“chunk 中间接触状态变化”的问题；A2C2 的修正头、TIDAL 的双频、SmolVLA 的异步推理都指向同一结论：**快回路要独立于慢回路**。
- 轻量化的关键不是“参数少”，而是“快回路只做窄任务”：残差、夹爪、门控；语义仍由慢回路负责。

#### G.2 延迟预算

| 环节 | 典型 | 目标 | 备注 |
|---|---:|---:|---|
| 相机采样 | 33ms（30fps） | 33ms | 4 路；可降帧/降分辨率 |
| 基座推理 | 100–300ms | chunk 8–16 步 | 异步，不阻塞 act |
| 网络/序列化 | 5–20ms | <20ms | 同机/局域网 |
| 反射头 | 1–5ms | <10ms | MLP/GRU，<10M 参数 |
| 动作下发 | 10–20ms | <20ms | API 位置目标 |
| **快回路总延迟** | — | **p99 <50ms** | 接触修正的最小目标 |

- 如果基座 p99 >300ms：增大 chunk、降分辨率、减相机路数、换更小基座；不要用“等一等”掩盖。
- 如果快回路 p99 >50ms：反射头太大/输入太多；先做确定性 P 控制。
- 如果 N 端口并发导致 p99 漂移：每进程限流、共享编码器、批处理；soak 测试。

#### G.3 异步服务

```python
class AsyncBase:
    def __init__(self, model, max_stale=3):
        self.model = model
        self.max_stale = max_stale
        self.future = None
        self.chunk = None
        self.age = 0

    def submit(self, obs):
        if self.future is None:
            self.future = self.model.submit(obs)

    def poll(self):
        if self.future is not None and self.future.done():
            self.chunk = self.future.result()
            self.future = None
            self.age = 0
        elif self.chunk is not None:
            self.age += 1
        return self.chunk, self.age
```

- `max_stale`：chunk 过期阈值；超过则快回路降速/保持，不继续执行旧轨迹。
- 不要在 `act` 里 `future.result()` 阻塞；不要在接触阶段做同步推理。
- 记录 `chunk_age` 与 `p99`；这是赛后定位“动作过期”的关键。

#### G.4 反射头

**输入**（全部轻量）：

- 腕部 RGB 的浅层特征（ResNet-18/轻量 ViT，冻结或低 LR）；
- 当前 EE 位姿与目标位姿的差（6D）；
- 夹爪开度/命令/变化率；
- 基座 chunk 的当前步与下一步；
- TCP 参数（速度/驻留/闭合）；
- 接触门控信号（速度骤降/夹爪停变/视觉 flow）。

**输出**：

- 6D 残差位姿（或 joint 残差）；
- 夹爪增量（开/合/保持）；
- 门控 logits（继续/驻留/回退/重试）。

**结构**：

```text
wrist_feat(128) + pose_err(6) + gripper(3) + chunk(14) + tcp(8) + contact(3)
        → MLP(256) → MLP(256) → {Δpose(6), Δgripper(1), gate(3)}
```

- <10M 参数；CPU/GPU 都能 1–5ms。
- 先训练残差与门控，不训练完整动作；避免和基座抢语义。
- 用 `tanh` 限幅残差（例如 ±2cm/±5°），防止反射头把动作拉飞。

**训练损失**：

\[
L = \|a_{\text{reflex}} - a_{\text{demo}}\|_1
+ \lambda_g \mathrm{BCE}(g_{\text{gate}}, g^*)
+ \lambda_s \|\Delta\|_2^2
+ \lambda_c L_{\text{contact}}.
\]

- 延迟增强：训练时随机把 base chunk 替换为 0–300ms 前的旧 chunk；让反射头学会“用最新 obs 修正旧计划”。
- 扰动增强：在接触前/接触中平移物体/目标 2–5cm；标签用演示后续动作或恢复动作。
- 失败增强：抓空、滑落、插偏、拉链卡住；标签是回退/重观测/重试。

#### G.5 退路

1. 反射头置信度低 → 用基座 chunk；降低速度。
2. chunk 过期 → 保持当前位姿/零速；重新提交。
3. 接触信号矛盾 → 驻留 0.2s，重新观测；不要猛推。
4. 反射头输出超限 → 限幅；记录异常。
5. 任何异常 → 返回合法“保持”动作，不抛异常。

#### G.6 评估

- 离线：在留出演示上测残差误差、门控准确率、接触检测延迟。
- 在线：p50/p99、chunk 年龄、残差幅度、接触阶段成功率、恢复次数。
- 消融：无反射 vs 确定性 P vs 学习反射；同步 vs 异步；chunk 1/2/4/8/16。
- 反证：如果反射头在接触阶段没有降低失败率，或 p99 没改善，就不上线。

### H. TCP：任务柔顺剖面

#### H.1 参数

对任务 \(i\) 的阶段 \(j\)，定义剖面：

\[
\pi_{i,j}=\{v_{\text{app}}, d_{\text{dec}}, t_{\text{dwell}}, g_{\text{close}}, v_{\text{rel}}, t_{\text{settle}}, r_{\text{search}}, n_{\text{retry}}\}.
\]

| 参数 | 含义 | 紧配合先验 | 容错先验 |
|---|---|---:|---:|
| \(v_{\text{app}}\) | 接近速度 | 0.02–0.04 m/s | 0.06–0.10 m/s |
| \(d_{\text{dec}}\) | 接触前减速距离 | 2–5 cm | 1–2 cm |
| \(t_{\text{dwell}}\) | 接触后驻留 | 0.2–0.5 s | 0–0.1 s |
| \(g_{\text{close}}\) | 夹爪闭合量/余量 | 留 1–3mm | 闭合到物体宽度 |
| \(v_{\text{rel}}\) | 释放速度 | 低速先停 | 可边走边放 |
| \(t_{\text{settle}}\) | 释放后稳定 | 0.1–0.3 s | 0.05–0.15 s |
| \(r_{\text{search}}\) | 搜索半径 | 2–5 mm | 0 |
| \(n_{\text{retry}}\) | 重试次数 | 2–3 | 1–2 |

#### H.2 从演示提取

1. **分段**：用 EE 速度、夹爪事件、相对距离把 episode 切成 approach/contact/insert/release/retreat。
2. **统计**：每段的速度中位/IQR、驻留时长、夹爪开度、释放速度；按任务聚合。
3. **成功标签**：如果 demo 全部成功，统计是“成功演示的习惯”，不是“最优参数”；用扰动实验补失败样本。
4. **拟合**：若有成功/失败标签，用逻辑回归/梯度提升拟合
   \[
   P(\text{success})=\sigma(\beta_0+\beta_1 v_{\text{app}}+\beta_2 t_{\text{dwell}}+\beta_3 g_{\text{close}}+\cdots).
   \]
   没有标签时，用分位数 + 真机调试校准。
5. **迁移**：新任务用语言/视觉 embedding 找最近邻剖面；没有相似任务就用全局保守剖面。

#### H.3 运行时选择

- **不要用任务 ID 硬编码**。用语言 embedding + 当前视觉场景 + 阶段，选择剖面；这样对未见任务也能迁移，也降低“任务特定逻辑”的规则风险。
- 剖面选择器可以是一个小分类头（同一 checkpoint 的一部分），输出 3–4 个剖面簇；或最近邻检索。
- 如果规则不允许任务特定逻辑：只保留一个“全局剖面 + 接触自适应”，仍然比固定速度好。

#### H.4 在线自适应

- 接触早于预期 → 提前减速/驻留；接触晚于预期 → 继续低速搜索。
- 夹爪开度停变 → 可能抓住/卡住；驻留 + 小幅回退。
- 释放后物体未稳定 → 延长 settle；不要立即撤退。
- 连续两次失败 → 降速/增大搜索半径/换抓取点；不要重复同一轨迹。

#### H.5 校准

- 离线：在演示上回放，检查剖面参数是否落在数据分布内。
- 真机：每个 P1 任务 2–3 个调试槽；用 A/B（全局 vs 剖面）配对。
- 记录：接触时间、驻留、插入深度、释放速度、成功/失败；更新剖面。
- 安全：速度/力限幅；夹爪不要夹碎；人手进入时暂停。

### I. CGP：接触门控原语

#### I.1 原语

| 原语 | 作用 | 关键信号 | 完成谓词 |
|---|---|---|---|
| `align` | 把 EE/物体对齐到目标容差 | 位姿误差、视觉 | 误差 < tol |
| `approach` | 按 TCP 速度接近 | 距离、速度 | 到达减速点 |
| `contact` | 检测接触/阻挡 | 速度骤降、夹爪停变、flow 降低 | 连续 2–3 帧 |
| `dwell` | 停一下，让物理稳定 | 时间 | 达到 \(t_{\text{dwell}}\) |
| `search` | 小半径螺旋/扫掠 | 接触、力代理 | 找到座合/放弃 |
| `seat` | 低速压入/座合 | 位移-阻力、深度 | 到位/超时 |
| `release` | 按 TCP 释放 | 夹爪开度、物体位移 | 物体脱离 |
| `settle` | 释放后稳定 | 时间、物体静止 | 达到 \(t_{\text{settle}}\) |
| `retreat` | 沿法线撤退 | 距离 | 离开工作区 |
| `recover` | 回退/重观测/重试 | 失败类型 | 状态恢复 |
| `verify` | 检查子目标谓词 | 视觉/位姿/状态 | 谓词为真 |

#### I.2 接触检测

位置-only API 没有力传感器，但接触有运动学/视觉痕迹。定义接触分数：

\[
c_t = w_1 \mathbf{1}[\|\Delta p_t\|<\epsilon_p]
+ w_2 \mathbf{1}[|\Delta g_t|<\epsilon_g]
+ w_3 \mathbf{1}[\mathrm{flow}_t<\epsilon_f]
+ w_4 \mathbf{1}[\mathrm{progress}_t<\epsilon_s].
\]

- \(\Delta p_t\)：EE 位移；\(\Delta g_t\)：夹爪开度变化；\(\mathrm{flow}_t\)：腕部图像光流；\(\mathrm{progress}_t\)：向目标的距离变化。
- 连续 2–3 帧 \(c_t>\tau\) 才判接触，避免单帧噪声。
- 接触后不要继续用“位置误差”硬推；先驻留/回退/搜索。

#### I.3 插入伪代码

```python
def insert(ctx, target, prof):
    for attempt in range(prof.n_retry):
        align(ctx, target, tol=prof.align_tol)
        approach(ctx, target, v=prof.v_app, decel=prof.d_dec)
        if not wait_contact(ctx, timeout=prof.contact_timeout):
            search(ctx, radius=prof.r_search)
        if contact(ctx):
            dwell(ctx, prof.t_dwell)
            if verify_seated(ctx):
                release(ctx, prof)
                settle(ctx, prof)
                return True
            back_off(ctx, prof.backoff)
            search(ctx, radius=prof.r_search)
    return False
```

- `wait_contact` 超时 → 搜索，不要盲推。
- `verify_seated` 用视觉/位姿/深度；没有传感器时用“插入深度 + 物体不再动 + 夹爪开度稳定”组合。
- `release` 前确认子目标；不要插到一半松手。

#### I.4 释放与 settle

- **紧配合**：先停，再开夹爪；开度到物体宽度 + 余量；等待 0.1–0.3s；沿法线撤退。
- **堆叠/放置**：可边走边放，但释放后要 settle；如果物体晃动，等稳定再撤。
- **拉链/软物体**：释放前保持轻夹；不要突然张开；用张力/开度监测。
- **失败**：释放后物体掉落/移位 → `recover` 重新抓取；不要假装完成。

#### I.5 任务映射

| 任务 | 原语序列 | 关键风险 |
|---|---|---|
| PlugCharger | align → approach → contact → dwell → seat → release → verify | 插偏、插头转动、插座反光 |
| PlugInEthernet | align → approach → contact → search → seat → verify | 网线弯、端口小、视觉遮挡 |
| Unlock | align → insert key → turn → flip ring → verify | 钥匙没插到底、转角不对 |
| StackBowls | approach → lower → release → settle → verify | 碗沿碰撞、叠歪 |
| ZipUp | pinch → straighten → pull → verify | 拉链头滑、布动 |
| PourOutMedicine | grasp cap → turn → lift → pour → verify | 盖子滑、药丸散落 |
| SyringeWaterTransfer | grasp → draw → align → inject → verify | 针头/水面、气泡 |
| ToolboxStorage | pick → place → close lid → lock → verify | 长程漏步、锁没扣上 |

#### I.6 失败模式

| 失败 | 检测 | 处理 |
|---|---|---|
| 抓空 | 夹爪闭合到 0、无物体位移 | 重新抓；换抓取点 |
| 滑落 | 物体位移/掉落、夹爪开度突变 | 降速/增大闭合；重新抓 |
| 插偏 | 接触早、位置误差不降 | 回退 2–5mm；螺旋搜索 |
| 卡住 | 速度骤降、progress 停 | 驻留/回退；不要加力 |
| 双抓 | 夹爪开度异常大、物体重叠 | 释放重抓 |
| 释放过早 | 物体未到位、掉落 | 重新放置；延长 settle |
| 超时 | `T_left` 不足 | 安全 abort；保留已完成步骤 |

### J. SFX：成功率优先的执行策略

#### J.1 成功闸门

| 闸门 | 检查 | 不通过时 |
|---|---|---|
| `g_grasp` | 夹爪开度稳定在物体宽度；轻抬 0.5–1cm 物体跟随；腕部图像物体在指间 | 重新抓/换点；不要继续运输 |
| `g_target` | 目标可见/位姿置信度 > 阈值 | 重观测/搜索；不要盲放 |
| `g_align` | 位姿误差 < 任务容差 | 微调/重新对齐 |
| `g_time` | \(T_{\text{left}} > E[T_{\text{step}}]+T_{\text{reserve}}\) | 跳过可选项/安全 abort |
| `g_contact` | 接触分数连续 2–3 帧 > 阈值 | 搜索/驻留；不要硬推 |
| `g_verify` | 子目标谓词为真 | 恢复/重试；不要假装完成 |

**原则**：闸门不是“多加延迟”，而是“避免把错误带到下一步”。一次失败的重试比一次错误的完成便宜。

#### J.2 恢复优先于重试

- **撤销检测**：人手把已完成的子目标撤销（叠好的毛巾翻开、拉链拉开、盖子拧回、插头拔起、锁拿走、碗拿走）。检测方式：子目标谓词从真变假 + 人手/物体运动。
- **恢复**：只修复被撤销的部分，不从头重跑；保留其他已完成状态。
- **重试**：只用于“本步失败但状态未变”的情况；重试前先回退/重观测。
- **abort**：时间不够/连续失败/安全风险；安全退出，保留已得步骤分。

| 失败类型 | 恢复动作 | 不要做 |
|---|---|---|
| 抓空 | 重观测 → 换抓取点 → 重抓 | 原地重复同一轨迹 |
| 滑落 | 降速/增大闭合 → 重抓 | 加速甩上去 |
| 插偏 | 回退 → 搜索 → 再插 | 加大力硬推 |
| 长程漏步 | 检查谓词 → 补做缺失步 | 从头重跑 |
| 人为撤销 | 暂停等人手离开 → 重定位 → 只修复被撤销步 | 继续执行旧计划 |
| 超时风险 | 跳过可选项 → 安全 abort | 赌最后一步 |

#### J.3 时间预算

- 每个任务维护 `E[T_step]`（演示均值 × 1.2 + 验证开销）。
- 预留 `T_reserve = 5s`（短任务）/ `8s`（长任务）用于恢复/验证。
- 如果 `T_left < E[T_step] + T_reserve`：跳过可选项（如整理、复检），保核心步骤。
- 如果连续 2 次重试仍失败：abort 或换策略；不要在一个步骤耗尽 180s。
- 短任务允许更多重试，但要设置“最大重试次数”；长任务优先保完成。

#### J.4 任务组合

用 Beta-Binomial 维护每个任务的成功率后验：

\[
p_i \sim \mathrm{Beta}(\alpha_i,\beta_i),\qquad
\hat p_i=\frac{\alpha_i}{\alpha_i+\beta_i}.
\]

边际收益：

\[
\Delta S_i=\frac{1}{32}(\hat p_i'-\hat p_i),\qquad
\mathrm{priority}_i=\frac{\Delta S_i\cdot c_i}{\mathrm{cost}_i},
\]

其中 \(c_i\) 是修复置信度，\(\mathrm{cost}_i\) 是调试/工程成本。

策略：

1. 先消灭 \(p_i=0\) 的任务/轴（最大边际收益）。
2. 再攻“高方差/高权重”的任务（紧配合、长程）。
3. 最后优化步骤分/时间（只在成功率相同的情况下值钱）。
4. 不要平均用力；P0 的 10 个任务已经占 31% 的分数。

#### J.5 方差与调试预算

- 单任务 10 次：SE≈14.5pp；不要把 +1 次成功当 +10pp。
- 用配对设计：同一任务、同一扰动，A/B 各 5 次；比较配对差。
- 用机制指标：接触驻留、插入深度、释放速度、time-to-contact、恢复次数；这些比 10 次成功率更敏感。
- 用任务级 bootstrap：按任务/轴重采样，报告 95% CI；不要只报总平均。
- 调试槽分配：P1 紧任务 2–3 槽；P0 放置 1–2 槽；P2 长程 1 槽；保留 1 槽给回归。

#### J.6 早提交

- 排名第三键是提交日期；先交一个“能跑、无崩溃、覆盖 32 任务”的基线。
- 基线要：合法模型、N 端口健康、无异常、超时可控、日志完整。
- 后续每次改进都保留回滚版本；不要为了最后一个点子错过截止。
- 提交前检查：模型卡、许可证、外部依赖、单模型合规、无任务硬编码、无隐藏人工干预。

#### J.7 主循环伪代码

```python
def run_episode(policy, instruction, obs0, budget=180):
    policy.reset(instruction, obs0)
    t0 = now()
    for step in policy.plan:
        if remaining(t0, budget) < estimate(step) + reserve(step):
            return policy.safe_abort(step)
        if not preconditions(step, obs0):
            policy.recover_or_replan(step)
            continue
        ok = policy.execute(step)
        if not ok:
            if policy.can_retry(step):
                policy.retry(step)
            else:
                policy.restore(step)
        if policy.undone(step):
            policy.restore(step)
    return policy.verify_all()
```

### K. WMD：世界模型蒸馏（可选）

#### K.1 决策门

- 只有在 **Tier A（6B + LDS + TCP + CGP + SFX）** 的 p99 仍 >80ms，或显存/N 端口成本过高时，才启动 WMD。
- 如果 Tier A 已满足 <50ms 接触回路、成功率稳定，**不做蒸馏**；不要为了“轻量”而牺牲成功率。
- 世界模型只在训练时做教师；在线不加载教师、不做视频预测、不做 MPC。

#### K.2 配方

1. **教师**：冻结的世界模型/VLA 世界模型分支；在演示帧上缓存中间特征。
2. **学生**：0.8B VLA（SmolVLA/TinyVLA 风格），动作头用 flow/diffusion 或回归。
3. **损失**：
   \[
   L = L_{\text{action}} + \lambda L_{\text{align}}(f_s, f_t) + \lambda_r L_{\text{reflex}}.
   \]
   对齐层用投影头，推理时丢弃。
4. **数据**：32 任务演示 + 扰动/恢复对；4 相机；语言复述。
5. **训练**：先冻结教师缓存特征，再训学生；1–2 周，1–2 张 GPU（量级估计，按实际资源调整）。
6. **评估**：32 任务离线 + 真机调试槽；与 6B 教师比。

#### K.3 验收标准

| 指标 | 阈值 | 不满足时 |
|---|---|---|
| 任务成功率 | 至少 24/32 任务不低于教师 5pp | 不蒸馏；保留 6B |
| 吞吐 | ≥2× 教师 | 不蒸馏 |
| 显存 | <4GB/进程 | 不蒸馏 |
| 接触阶段 | 不低于教师 5pp | 加反射头/数据 |
| 延迟 | p99 <50ms | 不蒸馏 |

**结论**：WMD 是“资源不够时的降级方案”，不是本轮的主押注；主押注仍是 LDS/TCP/CGP/SFX。

### L. 数据引擎与训练

#### L.1 接触相位挖掘

- 对每个 episode：计算 EE 速度、夹爪开度/变化率、左右 EE 相对距离、目标相对位姿。
- 分段：approach（速度高、距离降）、contact（速度降/夹爪停变）、insert（低速/微动）、release（夹爪开）、retreat（距离增）。
- 统计每段的 \(v_{\text{app}}, t_{\text{dwell}}, g_{\text{close}}, v_{\text{rel}}, t_{\text{settle}}\)。
- 产出：每任务一张“接触剖面卡”；异常 episode 单独标记（失败/重试/人手干预）。

#### L.2 扰动与恢复对

| 扰动 | 生成方式 | 训练目标 |
|---|---|---|
| 位置 | 物体/目标平移 ±2–5cm | 重新对齐/抓取 |
| 背景 | 2.5D 纹理替换/光照 | 视觉鲁棒 |
| 干扰物 | 在工作区插入相似物体 | 目标选择/关系推理 |
| 未见物体 | 留出物体/类别 | 语义泛化 |
| 人为干扰 | 人手遮挡/撤销子目标 | 暂停/重定位/恢复 |
| 延迟 | 旧 chunk 0–300ms | 反射修正 |
| 接触误差 | 插偏 2–5mm/角度 2–5° | 搜索/座合 |

**恢复对**：在接触前/中施加扰动，取“演示后续成功轨迹”作为恢复目标；训练策略“从扰动状态恢复到完成”，而不是“从头重跑”。

#### L.3 训练配方

- **基座**：WLA-1.0（6B，Apache-2.0）LoRA/全参微调；4 相机；语言；chunk 8–16；30fps。
- **输入**：`head_stereo_left/right`、`wrist_left/right`；`image_resize` 320/256；`obs_delta_indices` 只取当前+少量历史。
- **动作**：EE 位姿增量 + 夹爪；或 joint 目标；离线各测，选延迟/成功率更好的。
- **反射头**：冻结基座编码器，训练 2–4 层 MLP/GRU；延迟/扰动增强；<10M 参数。
- **联合**：如果显存允许，端到端低 LR 联合训练；否则分阶段。
- **正则**：动作限幅、速度平滑、chunk 一致性；避免高频抖动。
- **数据卫生**：不把任务 ID/坐标当输入；不用测试集调参；披露外部数据/权重。

#### L.4 评估

- **离线**：动作 L1/L2、接触检测延迟、门控准确率、恢复成功率。
- **在线**：每任务 10 次；按轴拆；机制指标；失败分类。
- **回归**：每次改动跑 P0 的 3–5 个任务，确认没有掉点。
- **真机安全**：限幅/急停/人手检测；先低速，再提速。

| I16 | **ContactMiner** 接触相位挖掘 | 从 33k 演示里挖“慢/停/放”的习惯 | **新增** | P0 | 新押注 |
| I17 | **Portfolio** 任务组合/统计功效 | 用 Beta-Binomial + 功效计算分配调试预算 | **新增** | P1 | 新押注 |

#### N.2 本轮主押注：I14 TCP

- **动机**：演示显示紧任务最后几毫米“慢 + 停”，容任务“边走边放”；全局降速会拖长长任务，且对容任务无收益。
- **差异**：不是“更慢的 VLA”，而是“按任务/阶段查表/学习的柔顺剖面”；参数少、可解释、可校准。
- **可行性**：参数从演示统计 + 真机调试得到；不需要新模型；可与任何基座组合。
- **资源**：1 人 × 2 周；数据挖掘脚本 + 剖面表 + 运行时查表。
- **步骤**：W2 挖剖面；W3 接 CGP；W4 调试槽 A/B；W5 校准。
- **风险**：规则不允许任务特定逻辑；用语言/视觉 embedding 选择剖面，不用任务 ID；保留全局回退。
- **反证**：紧任务 A/B 无差异/更差 → 放弃。

#### N.3 本轮主押注：I15 CGP

- **动机**：位置-only API 下，最后几毫米靠“撞/推”不可靠；需要可验证的接触原语。
- **差异**：不是“加一个力控器”，而是“用运动学/视觉接触信号门控的位置原语”；不违反 API。
- **可行性**：全部用位置目标 + 夹爪开度实现；接触检测用速度/夹爪/flow。
- **资源**：1 人 × 2–3 周；原语库 + 状态机 + 离线回放。
- **步骤**：W2 接触检测；W3 原语；W4 调试槽；W5 失败恢复。
- **风险**：接触检测误判；用多信号 + 连续帧 + 驻留；保留人工调试。
- **反证**：接触检测延迟 >100ms 或误报导致更多失败 → 退回“慢速 + 重试”。

#### N.4 数据与统计：I16 + I17

- **I16 ContactMiner**：把 33k 演示切成 approach/contact/insert/release/retreat；产出每任务剖面卡；这是 TCP 的数据基础。
- **I17 Portfolio**：用 Beta-Binomial 后验收敛任务成功率；用功效计算决定调试槽；先消灭 0%，再攻高杠杆；不要平均用力。
- **差异**：第 7 轮已有“任务组合”概念，但没有把“统计功效/调试槽噪声”写进决策；本轮把它变成可执行的计算器。
- **风险**：真实 \(p_i\) 未知；先用占位/自有基线，赛后更新；不要用 10 次结果过度拟合。

#### N.5 合规与部署：I19 + I20

- **I19 ModelCard**：写明基座、反射头、训练数据、频率、许可证、外部依赖、单模型边界；这是“防归零”，也是评审可信度。
- **I20 LatencyHarness**：记录 p50/p95/p99、chunk 年龄、N 端口、内存/热；4 小时 soak；不要只测单次。
- **差异**：第 7 轮的 FLEET 是清单；本轮把它变成可运行测试台 + 可披露模型卡。

- M1（W2）：TCP 剖面卡 + 接触检测可用。

### R. 开放问题

1. 真实排行榜/运行视频何时发布；`generated_from` 何时不再是 `gen_leaderboard.py`。
2. 任务介绍表格（Feishu wiki/sheet）里 10 次测试的逐任务设定；目前只有 `info.json` 的泛化备注。
3. 步骤分聚合公式：trial 平均？任务平均？是否归一化？
4. N 的准确值；调试槽可用次数/成本；是否允许 30–50 次自定义调试。
5. “单模型”是否允许同一 checkpoint 内的辅助反射头独立高频执行；模型卡怎么写。
6. 官方是否允许外部数据/预训练权重；许可证边界；WLA-1.0 的 Apache-2.0 是否可直接商用。
7. API 是否可能开放力/刚度/力矩；如果开放，CGP 可升级为真正阻抗控制。
8. 人为干扰的具体协议：人手进入工作区是否暂停计时；撤销后是否允许恢复。
9. 视觉输入是否允许降分辨率/裁剪；`obs_delta_indices` 的语义是否会影响评分。
10. 真实基线的 per-task 成功率；没有它，任务组合只能先用先验。

**会推翻本轮判断的证据**：

- 真实榜首 >60%，且失败不在接触/长程/干扰；
- 官方开放力控，行为柔顺的边际收益下降；
- 单模型规则禁止任何辅助头/多频率执行；
- 全量演示统计显示紧任务没有“慢/停”习惯；
- 10 次调试槽的配对实验显示 TCP/CGP 无收益。
