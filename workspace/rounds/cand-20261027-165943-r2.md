# 第 2 轮 · 研究循环 / 第 8 轮 · 赛事迭代：低成本技能组合 + 局部 MPC 最后一公里

> 检索/复核日期：**2026-10-27（UTC）**。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「低成本方案」「技能组合」「模型预测控制」。我先用官方参赛手册和一手数据把这三个词钉死，再合成主判断：**榜单头部方案（无论占位与否）共同暴露的不是语言 grounding，而是“最后一步/最后一个边界”的执行可靠性；最低成本的攻法不是再训一个更大的端到端模型，而是把全局语义留给一个已对齐的 6B 基座，把技能边界交给技能图，把最后 5 厘米交给确定性的局部 MPC 与安全滤波。**

> **本轮最重要的更正（会影响上一轮结论）**：官方参赛手册明确写了排名规则——**先按 32 任务总平均成功率排序，成功率相同才看总平均步骤分，仍相同看提交日期**。上一轮把“成功率 + 步骤分”当成近似同等权重，方向没错（终局放置仍是成功闸门），但**步骤分只是 tie-break**，不能拿“步骤分占 60%”去论证主预算。主预算必须围绕“把整条 episode 做成”而不是“多拿几步部分分”。另外，官方排行榜截至本轮仍是占位/演示数据，用户提到的“榜首不到 30%”与占位 JSON 的 29.7% 一致，但**不能当作真实排名**；我把它降级为弱先验，并用真实的 RoboChallenge Table30 做外部校准。

## 0. 本轮先核实：五个会改变判断的事实

### 0.1 参赛手册公开了评测算术：320 次真机试次、成功率优先、单模型

官方参赛手册（中文 [S2]、英文 [S3]）给出了此前缺失的关键规则：

- **32 任务 × 每任务 10 次独立运行 = 320 次真机试次**；10 次里 5 种泛化类型各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
- **单次任务最长 180 秒**，超时记失败，并按执行情况计算步骤分。
- **排名：总平均成功率优先；成功率相同看总平均步骤分；仍相同看提交日期。**
- **只允许一个模型完成全部 32 个任务，不得按任务混用多个模型**；但对模型类型不限（World Model、VLA 均可）。
- 选手自部署，平台只做远程 API 调用；每队可获得 32 个任务的全部真机数据。

这条规则把上一轮的“放置是闸门”从“权重论证”升级成“排名论证”：**终局步骤决定 success，success 决定排名；步骤分只在 success 打平时才重要。** 因此任何“只提高部分分、不提高整条成功率”的优化，边际价值比上一轮估计的更低；任何“让最后一步更容易成功”的优化，边际价值更高。

同时，320 次试次给了统计功效的硬约束：若真实成功率 p≈0.30，单次评测的标准误约 **2.56pp**（sqrt(0.3×0.7/320)）。+3pp 只有约 1.2 个标准误，不足以保证排名变化；**+5pp 才是值得作为主目标的量级**（约 2 个标准误）。这决定了本轮所有方案必须瞄准“至少 +5pp 成功率”，而不是零散的 +1~2pp。

### 0.2 数据规模确认：约 33k episodes / 169h，上一轮的“33k”成立

我直接读了 HuggingFace 的 `meta/info.json`（不是二手转述）：

| 数据集 | episodes | frames | fps |
|---|---:|---:|---:|
| G1_Dex1_HangCup [S10] | 1,043 | 194,564 | 30 |
| G1_Dex1_StackBowls [S11] | 979 | 295,609 | 30 |
| G1_Dex1_PlugCharger [S12] | 1,022 | 463,451 | 30 |
| G1_Dex1_OrganizeStationery [S13] | 1,028 | 738,414 | 30 |

第三方汇总页给出 32 个 repo 合计 **33,276 episodes、18,282,246 frames、约 811GB、Apache 2.0** [S14]；官方任务页写 32,000 演示 / 169 小时 [S1]。两者一致。上一轮的“33k”判断成立，且每个任务约 1k 条、30fps、四路相机、EE 位姿双坐标系，足以支撑技能级重标注和动作头微调。

需要解释一个容易误判的细节：HuggingFace 上另一个旧 collection（`unibot-v1-challenge`）仍显示 HangCup 44 条等旧数字 [S9]；但 `unibot-v1-challenge-dataset` collection 已显示 HangCup 1.04k，且 `meta/info.json` 的 `lastModified` 是 **2026-10-14**。结论：**全量数据已在 10 月中旬落地，旧 collection/旧帖是预览快照，不要再用 44 条做规划。**

### 0.3 榜单仍是占位：<30% 不能当真实排名，但 8 个模型阵容有信息量

本轮再次核对：

- `leaderboard_data.json` 仍带 `"generated_from": "gen_leaderboard.py"`，8 个模型、256 条 task_metrics 是脚本生成 [S6]。
- `leaderboard.html` 页面能渲染出 8 行表格，但页面底部仍是“即将发布 / Coming Soon” [S5]。
- `runs.html` 仍是“即将发布”，`details.html` 仍是“加载中 / Loading” [S7]。

所以，**用户看到的“榜首 29.7%”与占位 JSON 的第一行完全一致，但不能作为真实榜单结论**。我把它当“弱先验”而不是“事实”：如果这个结构有参考价值，它说明 8 个模型的成功率挤在 **20.5%–29.7%** 的 9.2pp 窄带里，步骤分比成功率高约 **8.6pp**（39.0 vs 29.7 等）。翻译成失败模型：**大多数失败不是“一步都做不了”，而是“做了大部分步骤、倒在最后一步/最后一个边界”**。这与 0.1 的成功率优先规则、以及 0.5 的外部基准相互印证。

占位阵容本身覆盖了 2026 年主流的 8 类方案，仍有分析价值：MolmoAct2（Ai2，VLM + flow-matching 动作专家）、WALL-OSS-0.5（X Square，4B VLA / 3B VLM 骨干 + gradient-bridge）、DreamZero（14B 视频扩散 World Action Model，7Hz 实时闭环）、Spirit-v1.5（数据多样性路线）、DM0（Dexmal，2B embodied-native；三阶段 + 动作专家梯度隔离）、PI-0.5（3B 通才 VLA）、GigaBrain-0（world-model 生成数据 + RGBD + embodied CoT）、GR00T N1.5（NVIDIA 3B，数据金字塔 + 人类/仿真/视角迁移）。这些不是随机名字，而是真实存在的模型家族；它们各自的公开论文/博客恰好能解释“为什么都会卡在最后一步”。

### 0.4 官方基座 WLA-1.0-Base：6B、Apache 2.0、单卡 24GB 可微调

宇树已经开源了与赛事同源的基座 **UnifoLM-WLA-1.0-Base** [S16][S17]：

- 6B 参数，checkpoint 约 12.5GB，Apache 2.0；
- 官方微调配方默认**冻结 VLM 主干，只训练动作专家（DiT 头）和 robot-state projector**，面向**单卡 24GB**；也支持 LoRA；
- 训练数据约 2,500 小时、64 个任务（54 个桌面 + 10 个全身），支持 Dex1 两指夹爪 [S18]；
- 官方没有公开它在 UniBot 32 任务上的成功率（这点很重要：基座不是“已知答案”，必须自己测）。

这条事实把“低成本方案”从口号变成可执行的基线：**我们不需要从零训练一个 6B/14B 模型；默认从 WLA-1.0-Base 出发，冻结 VLM，只改动作头和技能条件，单卡就能迭代。** 这也意味着研究火力可以集中到“技能结构 + 推理期控制”，而不是“再堆预训练”。

### 0.5 真实外部基准 RoboChallenge Table30：通才-专家差距与能力瓶颈

UniBot 榜单是占位，但 RoboChallenge Table30 是真实、公开、持续更新的真机榜单 [S19][S20]：

- 专家（Specialist）榜首 Era0 64.33%，DM0 62.00%，Spirit-v1.5 51.00%，pi0.5 42.67%；
- 通才（Generalist）榜首 Lira 45.00%，Atlas 39.67%，**DM0_generalist 37.33%**，pi0.5_generalist 17.67%；
- 同一模型 DM0 专家 62.00% → 通才 37.33%，**通才-专家差距约 24.7pp**；pi0.5 42.67% → 17.67%，差距 25.0pp；
- 能力维度（2025 年度报告 / 2026-05 公开快照）[S21]：simple-pick 85%、manipulation 68.3%、classification 52%、**temporal/sequence 40%**、**softbody 13.3%**。

这组数字比占位榜可靠得多，且恰好对应 UniBot 的任务结构：UniBot 有大量 4–5 步长程任务（T16 FoldTowel、T17 OrganizeStationery、T31 OrganizePencilCase、T09 ToolboxStorage、T15 OrganizeTools、T18 PackBag、T22 SpellRobot、T28 StoreEarphones）和软体/拉链/倾倒任务（T16、T18、T19、T23、T31、T14、T32）。**通才模型的最大损失不在“看见/听懂”，而在“把多步串起来”和“把软体/接触做稳”。** 这正是本轮“技能组合 + 局部 MPC”要打的两个靶心。

## 1. 三个灵感词，各自钉到官方事实上

### 1.1 低成本：真正的成本不是“模型多大”，而是“每次迭代要烧多少 GPU 小时 + 真机槽 + 工程周”

UniBot 的成本结构很特殊：

- **数据免费**：33k 官方数据、Apache 2.0，不需要自采；
- **算力自付**：平台不托管模型，N 个端口要自己部署；
- **真机槽稀缺**：计分跑 320 trials/次，调试槽只测 1 个任务且不计分；
- **迭代次数比单次规模更值钱**：320 trials 的噪声约 2.56pp，想验证 +5pp 至少要做多轮离线筛选 + 少量真机确认。

所以“低成本方案”不是“用最便宜的模型”，而是**用最低的每次迭代成本，换取最多的有效实验次数**。具体到架构：

| 成本项 | 昂贵路线 | 低成本路线（本轮默认） | 差异 |
|---|---|---|---|
| 基座 | 从零训 14B WAM / 大 VLA | WLA-1.0-Base 6B，冻结 VLM，只训动作头/LoRA | 单卡 24GB 可跑，省 1–2 个数量级 |
| 数据 | 自采/实验室补数 | 官方 33k，技能均衡抽 8–12k | 零采集成本、零合规风险 |
| 技能标注 | 人工逐帧 | 离线 VLM/规则 + 10% 抽检 | 1–2 人周，无真机 |
| 控制 | 学习世界模型 + 在线规划 | 确定性 MPC/CBF，CPU 5–20ms | 无训练、可解释、低延迟 |
| 推理 | N 份全精度模型 | 4/8-bit + 共享后端 + 批处理 | 1 张 24–48GB 卡服务 N 端口 |
| 真机 | 频繁计分跑 | 离线筛选 + 2 个调试槽 + 1–2 次计分跑 | 真机时间花在验证，不花在调参 |
| 总计（估算） | 数月、数十张 GPU、> $100k | 6–8 人周、1–2 张 GPU、< $2k 云算力 | 待实测校准 |

这个成本结构有一个直接的研究含义：**把算力花在“推理期的结构化搜索/验证”上，比花在“把模型再放大”上更划算。** 2026 年已经有强证据：

- **SVA**（Search, Value, Act）[S43]：冻结 VLA 的 pass@1 只有 33%，pass@32 却到 92%——好动作已经在输出分布里，缺的是“选”。用轻量 Q 评估器做候选选择，真机平均成功率 42.8% → 55.6%（+12.8pp）；9B + SVA 比 27B 单发高 7pp，延迟还低 27%。作者的原话是“scaling test-time evaluation is more cost-effective than scaling model size”。
- **PACT-VLA** [S42]：冻结 pi0.5、30Hz、chunk=50、N=4 候选，用“提交前观测”选 chunk，真机 60% → 82%（+22pp），训练免费。
- **CereVLA** [S40]：冻结 SmolVLA + 8.06M 参数残差治理，SO-101 上 57.5% → 90.0%，残差推理 8.2ms + 后果模块 2.74ms。
- **RTCF** [S41]：训练免费、CPU 后处理 10.99ms，LIBERO-Long 61.6% → 68.6%。

这些结果不能直接外推到 UniBot（不同机器人、不同任务），但方向一致：**在 6B 基座已经“会做大部分动作”的前提下，最后几个点的提升更可能来自“候选选择 + 安全滤波 + 边界恢复”，而不是再训一个更大的模型。** 这就是本轮“低成本”的真正含义。

### 1.2 技能组合：32 个任务共享约 12 个技能，通才-专家差距可以用“技能条件化”而不是“多模型”来补

官方 `score_steps` 已经把每个任务拆成 2–5 个带权步骤（上一轮已抓全 32 个 `info.json`；本轮直接重抓触发 EdgeOne 风控，故沿用已保存的 T27 步骤结构 [S15]）。把这些步骤归并，32 个任务其实共享一组很小的技能：

| 技能 | 定义 | 典型任务 | 是否需要 MPC | 成功谓词 |
|---|---|---|---|---|
| REACH | 移动到预抓/预放位姿 | 全部 | 是（避障） | 位姿误差 |
| GRASP | 闭合夹爪并确认抓住 | 全部 | 否 | 夹爪闭合 + 物体随动 |
| LIFT | 抬到安全高度 | 全部 | 是（避障） | 物体高度/随动 |
| TRANSPORT | 运到预放位姿 | 全部 | 是（避障） | 无碰撞 + 位姿 |
| PLACE | 下放/释放到目标 | T01–T04、T06–T08、T13、T15、T20–T22、T24–T25、T27、T30 | 是（最后 5cm） | 支撑/稳定/相对关系 |
| INSERT | 对准并插入插头/网线 | T10、T26 | 粗对准 + 视觉伺服 | 到位/视觉关系 |
| PULL | 拔出电池/网线/销 | T05、T11、T30 | 粗对准 | 物体离开 |
| ROTATE | 拧钥匙/瓶盖/环 | T07、T12、T14 | 否 | 角度/视觉 |
| PRESS/CLOSE | 合盖/锁扣/按键 | T09、T17、T28、T29 | 否 | 状态/视觉 |
| ZIP | 咬合拉链并拉合 | T18、T19、T23、T31 | 否 | 拉链闭合 |
| POUR | 倾斜/倾倒 | T14、T32 | 否 | 目标容器液面 |
| FOLD | 折叠毛巾/布料 | T16 | 否 | 折线/形状 |

这张表是本轮的核心结构假设：**任务级语言指令不是最好的条件粒度；技能级条件 + 技能级验证才是。** 支持它的证据链很完整：

- **PrimitiveVLA** [S28]：把演示拆成可复用运动基元，推理期用 VLM 规划 + LLM 切换，数据效率和泛化都提升。
- **DeCo** [S29]：原子技能分解 + VLM 检索/调度 + 空间感知技能链，RVT-2/3DDA/ARP 在 12 个新任务上分别 +66.67%/+21.53%/+57.92%；真机仅 6 个原子任务训练，零样本完成 9 个新任务，+53.33%。
- **LiLo-VLA** [S30]：把“运输”和“交互”解耦，LIBERO-Long++/Ultra-Long 平均 69%，比 pi0.5 高 41%；真机 8 个长程任务 85%。
- **MUCO** [S31]：manipulation units 带局部目标、启动条件、可观测成功/失败判据；跨任务复用、失败不级联。
- **InSight** [S32]：把 VLA 变成“可 steer 的基元策略”，14 个基元的长程任务 80%，twist/pour 92–96%。
- **HSR** [S33]：层级技能检索，LIBERO +10.3%、真机 +21.3%。
- **SMoDP** [S34]：技能条件化的 MoE 扩散策略，只更新 13.7M 参数（3.4%）就在 LIBERO-10 few-shot 上比 MoDE+LoRA 高 31.5pp。
- **MoE-ACT** [S35]：195M 激活参数在 RoboTwin 2.0 上 62.0%，比 ACT 高 17.4pp，比 3.24B 的 pi0 还高 5.1pp。

这些结果说明：**技能组合不是“把模型拆小”的工程技巧，而是对“通才-专家差距”的结构性回答。** UniBot 规则禁止按任务混用多个模型，但允许一个模型内部有技能条件/专家路由；SMoDP 和 MoE-ACT 正好证明“单模型 + 技能路由”可以在小参数下接近甚至超过大模型。

技能组合的最大风险也被 2026 年的工作点出来了：**边界漂移**。SkillWeave [S36] 指出，演示者在采集时到达的技能边界，和部署时前一个技能策略实际到达的边界不是同一个状态分布；前一个技能的小误差会让后一个技能进入训练分布之外。这个问题不解决，技能组合会在长程任务上“每一步都还行，串起来就崩”。本轮的解法不是“再训一个更大的模型”，而是**handoff MPC + 边界扰动训练 + 技能谓词验证**（见 §3）。

### 1.3 MPC：世界模型应该是“局部的”，不是“全局的”

榜单头部的两条主流路线是：

- **全局 VLA**（MolmoAct2、Spirit、DM0、pi0.5、GR00T、GigaBrain）：用大模型把语言/视觉/动作端到端映射；
- **全局 WAM**（DreamZero、GigaBrain 的视频世界模型）：用视频扩散预测未来，再反推动作。

两者都在“语义/物理先验”上很强，但都有一个共同的成本/精度问题：**全局世界模型很贵，而且不直接解决最后 5 厘米的几何/接触问题。** DreamZero 是 14B、7Hz；MolmoAct2 的论文自己也说 reasoning-augmented policies 的 grounding 延迟很高；GigaBrain 需要 RGBD + 世界模型生成数据。UniBot 的 API 只给 RGB + 关节/EE 位姿，没有力/力矩，而且 N 个端口要自己部署——全局 WAM 的性价比在“最后一步”上并不高。

反过来，**局部世界模型**（已知 G1 运动学 + 简化碰撞几何 + 短时域 MPC）在最后 5 厘米上非常便宜且精确：

- **GPC** [S37]：冻结扩散策略 + 动作条件世界模型 + 轻量在线规划，推理期提升 BC，不改权重。
- **Warm-Starting Collision-Free MPC** [S38]：扩散模型做 warm start + 碰撞感知 MPC 精修，在严格时限下比采样规划器或任一单独组件都更可靠、延迟更低；真机 Panda 验证。
- **Multi-Link Safety Filtering** [S39]：五个椭球覆盖夹爪/腕/前臂，CBF 滤波，CPU p99 仅 **2.2ms**；碰撞率 65.62% → 27.27%，safe-success 29.35% → 50.43%；真机 SO-101 上 16 次里碰障碍 3 次 vs 未加滤波 11 次。
- **CereVLA / RTCF / PACT / PAV / CheckVLA** [S40]–[S46]：都在证明“推理期验证/残差/候选选择”可以用很小代价换到可观的成功率。

UniBot 的接口恰好支持这种局部 MPC：

- 动作空间可选 **EE 位姿**（`action.*_ee_pose_gripper_base`，6D）或关节目标；MPC 可以在 EE 空间规划，交给底层控制器做 IK/执行；
- 观测有 **左右高位 + 左右腕部四路 RGB**、双臂关节/EE 位姿、夹爪开度、下半身；没有力/力矩，但可以用 **EE 跟踪误差** 做接触代理；
- 动作是 **chunk**，一次 `get_action` 返回 T_a 步，评估器顺序执行；这意味着 MPC 不需要每个控制 tick 都跑，**每个 chunk 跑一次 5–20ms 的 MPC 完全在预算内**（chunk=16、30Hz 时预算约 533ms）；
- 官方数据集 30fps，控制频率未在 README 明确；本轮按 30Hz 假设，必须在调试槽实测（开放问题）。

所以本轮的 MPC 不是“运行时全物理仿真/RL”（上一轮已砍），而是**一个确定性的、任务无关的局部控制器 + 安全滤波器**：VLA 给“去哪/做什么”，MPC 给“怎么不撞、怎么对准、怎么在最后 5cm 稳住”。这也是“低成本”的一部分：MPC 在 CPU 上跑，不需要第二个学习模型。

把这张表和 0.5 的真实基准放在一起，头部方案的共同瓶颈可以收敛成四句话：

1. **长程复合误差**：temporal/sequence 只有 40%，每一步 90% 的成功率串 5 步就只剩 59%；技能边界没有显式验证，错误会级联。
2. **最后一步/最后 5 厘米**：放置、插入、合盖、拉链这些终局动作同时是 success 闸门和步骤分大头；全局模型输出的是 chunk，不是闭环的“对准—接触—确认”。
3. **通才-专家差距**：DM0 62.0 → 37.3、pi0.5 42.67 → 17.67；单模型覆盖 32 任务时，任务干扰/数据不均导致“每样都会一点、每样都不稳”。
4. **成本/延迟**：14B WAM 7Hz、6B VLA 多端口、reasoning 延迟；在自部署 + N 端口的约束下，单纯堆模型不可持续。

占位榜的“步骤分 − 成功率 ≈ 8.6pp”正好是第 2 条的弱证据：模型能做完大部分步骤，但最后一步没成。RoboChallenge 年度报告的原话更直接：**“For hard tasks, a model may make good progress, but still fail in the very last step.”** [S21] 所以本轮不去和头部比“谁的全局模型更大”，而是比“谁把最后一步/最后一个边界做得更可靠”。

## 3. 本轮主判断：全局语义交给 VLA，最后一公里交给技能图 + 局部 MPC

### 3.1 一句话架构：S-MPC（Skill-MPC）

```text
语言（官方 160 条复述之一）
        │
        ▼
技能图 SKG：32 任务 → 12 技能序列（来自官方 score_steps）
        │  当前技能 s、目标 g、成功谓词 φ
        ▼
┌───────────────────────────────────────────────┐
│ SVC：单 checkpoint 技能条件 VLA（WLA-1.0-Base）│
│  输入：4 路 RGB + proprio + 语言 + [SKILL:s]   │
│  输出：action chunk a_{1:H}                    │
└───────────────────────────────────────────────┘
        │
        ▼
┌───────────────────────────────────────────────┐
│ MPC-Lite：确定性局部控制器（仅刚体/放置/插入） │
│  - warm start：用 VLA chunk 做名义轨迹         │
│  - 代价：目标位姿 + 碰撞 + 平滑 + 关节限位     │
│  - 安全滤波：CBF/投影，保守 3cm  margin        │
│  - handoff：把状态对齐到下一技能的规范起始位姿 │
└───────────────────────────────────────────────┘
        │
        ▼
执行 chunk → 技能谓词验证 φ
   ├─ 成功 → 进入下一技能
   ├─ 失败 → 重试 / 换恢复技能 / 回退 VLA
   └─ 人为干扰/异常运动 → 暂停、重观测、重规划
```

这不是“VLA + 一个独立模型”，而是**一个 checkpoint + 一个确定性控制层 + 一个确定性技能图**：

- SVC 是唯一的学习模型；技能 token 是输入，不是第二个模型；
- SKG 是规则/状态机，来自官方 `score_steps`，不学习；
- MPC-Lite 是已知运动学 + 几何碰撞 + 短时域优化，不学习、任务无关、对所有任务用同一套代码；
- 这样满足“单模型完成全部 32 任务、不得按任务混用多个模型”的规则；MPC 是否被算作“模型”需要在模型卡中披露并向组委会确认（见 §6）。

### 3.2 为什么这能同时打中四个瓶颈

| 瓶颈 | S-MPC 的对应机制 | 证据 |
|---|---|---|
| 长程复合误差 | 技能图 + 每步谓词验证 + 失败重试/恢复；不把整条任务当一个黑箱 | MUCO/DeCo/LiLo/HSR；SkillWeave 的边界问题 |
| 最后 5 厘米 | MPC-Lite 对准/避障/缓放；handoff 到规范位姿 | GPC、warm-start MPC、CBF safety filter |
| 通才-专家差距 | 技能条件化单模型 + 技能均衡采样 + 技能级数据复用 | SMoDP、MoE-ACT、PrimitiveVLA、InSight |
| 成本/延迟 | 6B 单卡微调 + CPU MPC + 4/8-bit + 共享后端 | WLA 单卡 24GB；CBF 2.2ms；PACT/SVA 的 test-time scaling |

### 3.3 预期收益：先要 +5pp success，再谈步骤分

按 320 trials、p≈0.30、SE≈2.56pp：

- **+5pp success** ≈ 2 个标准误，是“值得押注”的最小量级；若占位榜的 9.2pp 窄带结构在真实榜单成立，+5pp 足以从榜尾跳到榜首附近。
- **+3pp success** 只有约 1.2 个标准误，不能保证排名；但步骤分 tie-break 仍可能受益。
- 终局步骤是 success 闸门：如果 q=到达终局的通过率（估 0.5–0.7），终局成功率 +Δ 对全局 success 的贡献约 Δ×q；+10pp 终局 ≈ +5–7pp 全局。这正是我们要在调试槽里验证的量。
- 可证伪点：若 T27/T10 调试槽里终局步提升 <5pp，或 MPC 碰撞率 >5%，或技能边界成功率 <70%，则本轮主假设不成立，回退到“纯 VLA + 轻量安全滤波 + 技能谓词”而不做 MPC 重投入。

### 3.4 与第 7 轮 PILOT 的关系：深化，不是推倒

| 关系 | 内容 |
|---|---|
| 保留 | WLA-1.0-Base 底座；SSG 的“公开步骤图”思想；OPT 的容器系释放位姿统计；SVL 的 settle-verify 思想；NRB 的官方 human 备注；DebugLoop 的调试槽发布门；FLEET 的 N 端口/状态隔离检查单 |

## 5. 本轮最值得做的三个实验（先证伪，再投入）

### 5.1 实验 A：技能边界诊断（离线，1 周）

- 从 32 任务各抽 50 条演示，用官方 `score_steps` + 夹爪事件 + EE 轨迹切段；
- 统计每个技能边界的“前一个技能终点 → 后一个技能起点”的位姿分布；
- 度量：边界状态方差、跨任务同技能的可迁移性、谓词可观测性；
- Go/No-Go：边界 F1 >0.85、谓词可观测率 >80%；否则先修标注，不训模型。

### 5.2 实验 B：MPC-Lite 离线回放（1 周）

- 用 G1 URDF + 简化碰撞体（桌面、容器、目标物）搭 MPC；
- 在演示的 EE 轨迹上做“warm start + 碰撞检查 + 目标位姿误差”回放；
- 度量：碰撞率、目标位姿误差、p99 延迟；
- Go/No-Go：碰撞率 <5%（回放理想 <1%）、p99 <20ms、目标位姿误差 <1cm（刚体任务）；否则缩小 MPC 适用范围（只做安全滤波，不做规划）。

### 5.3 实验 C：调试槽 A/B（1 个槽；先 T27，再 T10；每次只测 1 个任务）

- T27 StackBowls：终局“叠第三个碗”是放置闸门；T10 PlugCharger：终局“插入插排”是接触闸门；
- 对比：WLA 基线 vs +技能 token vs +MPC；每个配置 10 trials（单任务调试通道）；
- 度量：终局步成功率、整任务成功率、步骤分、p99 延迟；
- Go/No-Go：终局步 +5pp（离线 +10pp）、整任务 +3–5pp、无回归；否则回退到“技能 token + 安全滤波”，不做 MPC 规划。

这三个实验的设计原则是：**先用离线/单任务证伪，再花计分跑的真机时间。** 320 trials 的噪声太大，不能拿计分跑当调参器。

## 6. 风险与合规（先立后破）

- **单模型边界**：SVC 是唯一学习模型；SKG/MPC 是确定性代码。规则说“不得按任务混用多个模型”，我们的 MPC 是任务无关的同一套控制层，不是按任务切换的第二个策略。仍需在模型卡中披露，并向 `challenge_support@unitree.com` 确认 MPC/CBF 是否算“模型”。若算，回退到“纯 VLA + 轻量 CBF 安全滤波”或去掉 MPC 规划，只保留谓词验证。
- **外部数据**：公开手册只写了“每队可获得 32 任务全部真机数据”，没有明确允许外部数据；本轮默认只用官方数据，L2L 实验室补数降级为赛后/可选，避免合规风险。
- **榜单占位**：不能拿 29.7% 当真实目标；用 RoboChallenge/离线/调试槽做校准。真实榜单发布后要重跑“终局闸门”假设。
- **技能切分错误**：官方步骤是任务级文本，不是帧级标签；切分错误会污染技能 token。用 10% 人工抽检 + 谓词可观测性做门控；切分 F1 <0.85 就不进入训练。
- **边界漂移**：handoff MPC 能把状态拉回规范位姿，但会多花 1–3s；长程任务（T16/T17/T31）要限次数，避免 180s 超时。
- **MPC 位姿误差**：透明/小件/软体容器的 6D 位姿估计不稳；MPC 只用于刚体/容器类任务，软体/拉链/倾倒走 VLA + 视觉伺服；保守 3cm margin，失败回退 VLA。
- **无力反馈**：插入只能做到“视觉对准 + 跟踪误差代理 + 小步试探”，不能承诺高力控精度；T10/T26 作为“尽力而为”，不把全部收益押在插入上。
- **延迟**：候选选择 K=4 + MPC 可能超 chunk 预算；用自适应 K（高风险技能才 4）、缓存、p99 守卫；控制层 p99 >20ms 或总 p99 >400ms 就降 K/关 MPC。
- **量化精度**：4-bit 可能掉点；先 8-bit，再 4-bit A/B；掉点超过 2pp 就回 8-bit/多卡。
- **统计噪声**：320 trials、p≈0.3、SE≈2.56pp；主目标 +5pp；用 bootstrap CI，不以单次计分跑下结论。

### 0.3 预期收益（可证伪）

- **主目标**：320 trials 上整任务成功率 **+5pp**（p≈0.30 时约 2 个标准误；+3pp 只有约 1.2 个标准误，不作为主目标）。
- **机制目标**：终局步成功率 +10pp ⇒ 全局约 +5–7pp（q=到达终局的通过率，估 0.5–0.7）；技能边界成功率 ≥70%；MPC 碰撞率 <5%；控制层 p99 <20ms、总 p99 <400ms。
- **可证伪点**：若 T27/T10 调试槽终局步提升 <5pp，或 MPC 碰撞率 >5%，或技能切分 F1 <0.85，则本轮主假设不成立，回退到“技能 token + 轻量 CBF + 谓词验证”，不做 MPC 规划重投入。
- **排名含义**：如果占位榜的“成功率 20.5–29.7% 窄带、步骤分比成功率约 +8.6pp”结构在真实榜单成立，+5pp success 足以改变排名；但这是弱先验，必须用真实榜单/调试槽校准。

## 1. 事实核对（2026-10-27）

### 1.1 规则：320 次真机试次、成功率优先、单模型

官方参赛手册（中文 [S2]、英文 [S3]）原文要点：

- **“所有任务须基于同一模型完成，不得混合使用多个模型一起进行测试，但对模型类型不作限制（World Model、VLA 均可）。”**
- **“通才模型赛道：要求参赛选手提交的模型完成全部的 32 个任务，每个任务在不同的泛化评测场景中进行 10 次测试，计算每个任务的平均成功率，平均过程分，并计入排行榜。”**
- **“实时榜单按 32 个任务的总平均成功率进行排序，成功率相同时按总平均步骤分排序，若仍相同，则提交日期较早的模型排序靠前。”**
- **“每个任务执行 10 次独立运行，每次运行采用不同的泛化设定……10 次运行中包含以下 5 种泛化类型，每种类型各出现 2 次。”**
- **“每个任务单次真机执行最大允许执行时间为 180 秒，超时记为失败，并根据执行情况计算步骤分。”**
- **“每支参赛队伍可获得 32 个任务的全部真机采集数据，用于模型训练与调试。”**
- 选手自部署；平台只做远程 API 调用；平台不托管模型 [S2][S3][S4]。

**推导**：32 × 10 = **320 trials**；5 类泛化 × 每类 2 次；排名先看 success，再看 step score，最后看提交日期。**步骤分不是与成功率同权的主目标，而是 tie-break 与部分分诊断。**

**统计含义**：320 trials、p≈0.30 时，单次评测标准误约 **2.56pp**（sqrt(0.3×0.7/320)）。+5pp ≈ 1.95 SE，是值得押注的最小量级；+3pp ≈ 1.17 SE，不足以保证排名变化。所有实验以 +5pp 为主目标。

### 1.5 API：4 路 RGB、joint/EE 互斥、chunk、无 F/T、N 端口

从官方 `unibot_submission` README [S4]：

- **4 路 RGB**：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`，原生 **480×640**，HWC，RGB；
- **状态**：左右臂各 7 维关节；左右 EE 位姿（base 系，xyz 3 + rpy 3）；夹爪；下半身；`observation.language` 是**单字符串**，episode 内不变；
- **动作空间**：`control_space` 为 `"joint"` 或 `"ee"`，二者**互斥**；joint 用 `action.left_arm/right_arm`（7+7），ee 用 `action.left_ee_pose_gripper_base/right_ee_pose_gripper_base`（6+6）；
- **chunk**：`action_chunk_size` 是每个动作的前导时间轴长度，T_a ≥ 1；`obs_delta_indices` 决定观测键与时间堆叠；`image_resize` 决定图像分辨率；
- **无 force/torque**；控制频率未在 README 明确；官方数据 30fps，本轮按 30Hz 假设，必须在调试槽实测；
- **N 端口**：从 8765 开始连续 N 个端口；N 必须与机器人数一致；每个端口可各自加载一份模型，也可**共享一个模型**（需要并发安全/批处理）；示例 N=3；N 的具体值由官方另行公布 [S4]。

## 2. 成本模型：为什么 S-MPC 是低成本方案

### 2.1 成本结构：真正的成本是“每次迭代的 GPU 小时 + 真机槽 + 工程周”

UniBot 的成本结构很特殊：

- **数据免费**：33k 官方数据、Apache 2.0，不需要自采；
- **算力自付**：平台不托管模型，N 个端口要自己部署；
- **真机槽稀缺**：计分跑 320 trials/次；调试槽只测 1 个任务且不计分；
- **迭代次数比单次规模更值钱**：320 trials 的噪声约 2.56pp，想验证 +5pp 至少要多轮离线筛选 + 少量真机确认。

所以“低成本”不是“用最便宜的模型”，而是**用最低的每次迭代成本，换取最多的有效实验次数**。

### 2.2 与“更大模型”的对比

| 成本项 | 昂贵路线 | S-MPC（本轮默认） | 差异 |
|---|---|---|---|
| 基座 | 从零训 14B WAM / 大 VLA | WLA-1.0-Base 6B，冻结 VLM，只训动作头/LoRA | 单卡 24GB 可跑，省 1–2 个数量级 |
| 数据 | 自采/实验室补数 | 官方 33k，技能均衡抽 8–12k | 零采集成本、零合规风险 |
| 技能标注 | 人工逐帧 | 离线 VLM/规则 + 10% 抽检 | 1–2 人周，无真机 |
| 控制 | 学习世界模型 + 在线规划 | 确定性 MPC/CBF，CPU 5–20ms | 无训练、可解释、低延迟 |
| 推理 | N 份全精度模型 | 4/8-bit + 共享后端 + 批处理 | 1 张 24–48GB 卡服务 N 端口 |
| 真机 | 频繁计分跑 | 离线筛选 + 2 个调试槽 + 1–2 次计分跑 | 真机时间花在验证，不花在调参 |
| 总计（估算） | 数月、数十张 GPU、> $100k | **6–8 人周、1–2 张 GPU、< $2k 云算力** | 待实测校准 |

> 以上是**工程估算**，不是报价：实际取决于云价、团队人数、是否已有 G1/URDF、是否需要租用调试槽。写进报告是为了说明“为什么这套方案可以反复迭代”，不是承诺绝对金额。

### 2.3 低成本设计规则（硬约束）

1. **一个学习模型**：SVC 是唯一 checkpoint；SKG/MPC/CBF 是确定性代码；不按任务切模型。
2. **冻结 VLM**：默认只训动作头 + robot-state projector；LoRA 只在动作头掉点 >3pp 时启用。
3. **官方数据 only**：默认不采外部数据；L2L 默认 OFF，避免规则不确定。
4. **CPU 控制**：MPC/CBF 不上 GPU；不训练第二个世界模型。
5. **4/8-bit + 共享后端**：先 8-bit，再 4-bit A/B；N 端口共享一个模型，状态隔离。
6. **离线筛选优先**：任何改动先在离线/回放/TCLB 上过门，再上调试槽，最后上计分跑。
7. **可降级**：技能 token 可 dropout；MPC 可关；TTC 可关；任何组件失效都不应让整条 episode 崩。

### 3.3 技能切分算法（离线，1 周）

输入：官方 33k episodes（四路 RGB、EE 位姿、夹爪、语言、`score_steps`）。

1. **解析步骤**：从 `score_steps` 抽取动词/名词/权重；用规则 + 小模型映射到 12 技能候选。
2. **夹爪事件**：检测 gripper close/open；作为 GRASP/PLACE/PULL 的强边界。
3. **轨迹事件**：EE 速度/加速度局部极小、接触代理（跟踪误差）峰值、物体位移突变；作为 INSERT/PLACE/PULL 的弱边界。
4. **单调对齐**：用动态规划把候选边界对齐到步骤序列（单调、权重匹配、允许 1 步跳过）；目标函数 = 步骤匹配 + 边界平滑。
5. **谓词标注**：每个段末尾用确定性谓词（位姿/夹爪/物体关系）+ 10% 人工抽检；不可观测的谓词标为“未知”，不进入训练。
6. **质量门**：技能切分 F1 >0.85、谓词可观测率 >80%；否则只保留任务级 + 终局技能 token，退回“弱技能”模式。

**弱技能模式**（fallback）：不训练中间技能 token，只在终局前注入 `[SKILL:PLACE]`/`[SKILL:INSERT]` 等终局 token；SKG 仍做谓词验证与重试。这样即使切分不完美，也能拿到“最后一步”的主要收益。

### 3.4 技能均衡采样

33k episodes 的技能分布是长尾：PLACE 占多数，ZIP/FOLD/INSERT/PULL 很少。训练时：

- 统计每个技能的有效段数 n_s；
- 权重 w_s ∝ 1/sqrt(n_s)，上限 3×，下限 0.5×；
- 每个 batch 保证每个技能至少 1 段（稀有技能优先）；
- 每个任务 ≤5% batch，防止长程任务被短任务淹没；
- 每 epoch 8–12k episodes（250–300GB 子集），避免 811GB 全量 I/O；
- 稀有技能（ZIP/FOLD/INSERT/PULL）额外 2–3× 过采样；PLACE 0.5× 降采样；
- 验证集按任务分层，不按技能分层（防止“技能会了、任务不会”）。

### 3.5 技能 token 格式

在原始语言后追加内部 token（评估器看不到）：

```text
[SKILL:PLACE] [OBJ:bowl_3] [TARGET:bowl_2] [REL:on_top] [PHASE:0.0]
```

- **为什么不加新 embedding**：WLA 的 VLM 已经能处理文本 token；追加 token 不改架构、不加第二个模型；动作头通过 cross-attention 读取。
- **训练**：技能 token 与语言一起输入；10–20% 概率 dropout 技能 token，让模型在没有 token 时仍能工作（fallback）。
- **推理**：SKG 根据当前步骤发出 token；如果 SKG 不确定，发 `[SKILL:AUTO]`，退化为任务级条件。
- **风险**：token 分布偏移；用 dropout + 任务级混合训练缓解；token 不是“硬编码动作”，只是条件。

### 3.6 谓词、边界与失败恢复

每个技能有：

- **成功谓词 φ(s)**：确定性、可观测；例如 PLACE 的“物体在目标容器内/上、稳定 0.5s、无掉落”；
- **失败谓词 ψ(s)**：物体掉落、碰撞、跟踪误差超阈值、超时、目标关系不成立；
- **超时**：每个技能有最大时长（短技能 8–12s，长技能 20–30s）；总时长守卫 150s（留 30s 余量）。

| 技能 | φ 示例 | ψ 示例 | 失败动作 |
|---|---|---|---|
| REACH | EE 位姿误差 <1cm/5° | 碰撞/超时 | 重规划；MPC 避障 |
| GRASP | 夹爪闭合 + 物体随动 | 夹空/物体滑 | 重抓（≤2 次） |
| LIFT | 物体高度 >桌面+2cm | 掉落 | 重抓/回退 |
| TRANSPORT | 到预放位姿、无碰撞 | 碰撞/掉落 | MPC 重规划 |
| PLACE | 支撑/稳定/关系成立 | 掉落/偏移/超高 | 微调/重放（≤2 次） |
| INSERT | 相对位姿到位/视觉 seated | 卡住/偏斜/超时 | 退回 2cm 重对准（≤2 次） |
| PULL | 物体离开、其他未动 | 拔不动/带倒其他 | 换抓点/回退 |
| ROTATE | 角度变化 | 打滑 | 重抓 |
| PRESS/CLOSE | 状态变化 | 未闭合 | 重按/回退 |
| ZIP | 拉链闭合/打开 | 卡住/脱轨 | 重咬合/回退 |
| POUR/TRANSFER | 目标液面变化 | 洒出/未出液 | 调整角度/回退 |
| FOLD | 折线/形状 | 拖拽/未折 | 重抓/回退 |

**边界 handoff**：当 φ(s) 成立、进入下一技能时，MPC 把 EE 从“实际终点”移到下一技能的“规范起始位姿”（由演示统计得到），最多 1–3s；长程任务最多 2 次 handoff，避免 180s 超时。这个动作就是 SkillWeave 所说的“bridging motion”，但我们用确定性 MPC 做，不训练额外策略 [S36]。

### 4.2 SVC：技能条件化单 checkpoint

- **底座**：WLA-1.0-Base 6B（Apache 2.0，12.5GB）[S17][S18]。
- **冻结策略**：默认冻结 VLM（`qwen_vl_interface`），训练动作专家（DiT）头 + robot-state projector；如果动作头掉点 >3pp，再对动作头/LoRA 做轻量适配 [S16]。
- **输入**：4 路 RGB（可 resize 到 224/256）；双臂关节/EE、夹爪、下半身；语言 + 技能 token；可选 1–2 帧历史（`obs_delta_indices`）。
- **输出**：EE 6D delta 或 joint target；夹爪开合；H=16 的 chunk（与 `action_chunk_size` 对齐）。
- **为什么用 EE**：MPC 在 EE 空间规划更直接；官方 API 支持 `ee` 模式；如果 `ee` 模式在调试槽表现差，回退 `joint` 模式，MPC 在关节空间做。
- **为什么冻结 VLM**：24GB 单卡、成本低、保留语义泛化；技能条件通过 token 注入，不改 VLM 权重。
- **技能条件的作用**：把“任务级长程”切成“技能级短程”，降低动作头要建模的分布；同时让同一 checkpoint 在不同任务间复用技能。

### 4.3 MPC-Lite：只做最后 5 厘米

- **作用域**：REACH/LIFT/TRANSPORT/PLACE/INSERT/PULL 的刚体桶；**不用于** FOLD/ZIP/POUR/软体/液体。
- **输入**：当前 EE 位姿/关节、目标位姿（来自 OPT 统计或视觉）、碰撞环境（桌面、容器、目标物、臂杆椭球）、VLA 的 chunk（warm start）。
- **输出**：精修后的 chunk 或速度指令；交给底层控制器执行。
- **为什么不是全物理 MPC**：G1 全身动力学 + 接触 + 柔体太贵；最后 5cm 用运动学/双积分 + 几何碰撞足够；全物理仿真留给赛后。
- **为什么是确定性**：无训练、可解释、CPU 5–20ms、不会引入第二个学习模型；符合低成本 + 单模型。

### 4.4 BSR：边界 / Handoff

**问题**：SkillWeave 指出，演示者到达的技能边界 ≠ 部署时前一个策略实际到达的边界；前一个技能的小误差会让后一个技能进入 OOD 状态 [S36]。这是技能组合在长程任务上“每一步都还行、串起来就崩”的主因。

**三个机制**：

1. **Handoff MPC**：进入下一技能前，MPC 把 EE 从实际终点移到下一技能的规范起始位姿（由演示统计的均值/中位数得到）；限时 1–3s；只做 1 次，不反复。
2. **边界扰动训练**：从演示中采集技能 A 的终点状态，扰动物体/EE 位姿（σ=1–2cm/2–5°），渲染或回放得到观测，训练技能 B 从扰动状态到达目标；如果渲染太贵，只用 handoff MPC + 真实回放，不做大规模合成。
3. **谓词验证**：φ(s) 不成立就不进入下一技能；宁可重试当前技能，也不把错误传给下一个技能。

**预算**：长程任务（T16/T17/T31）最多 2 次 handoff；每次 1–3s；总时长守卫 150s。若 handoff 后仍失败，回退到任务级 VLA（无技能切分），避免死循环。

### 4.5 TTC：测试时候选选择

- **触发条件**：高风险技能（PLACE/INSERT/PULL）或 VLA 不确定（多候选方差大）；低风险技能不触发，省延迟。
- **候选**：K=2–4 个 chunk；从同一观测采样；共享前缀/批处理。
- **评分**：FlowRes（PACT-VLA）——用冻结 VLA 在“提交前观测”上预测的速度方向，与候选 chunk 的隐含流方向比较；残差最小者胜 [S42]。
- **备选**：SVA 的轻量 Q 评估器 [S43]；但 Q 评估器需要额外训练，默认不用，除非 FlowRes 在调试槽无效。
- **延迟**：K=4 时增加约 50–150ms；如果 p99 超 400ms，降 K=2 或关闭 TTC。
- **合规**：TTC 复用同一个冻结 VLA，不引入第二个模型；如果组委会认为候选选择是“多模型”，关闭 TTC（它是可选增益，不是主假设）。

### 4.6 LCR：低成本运行时

- **量化**：先 8-bit；4-bit 只在离线/调试槽不掉点 >2pp 时启用。
- **共享后端**：N 个端口共享一个模型进程；请求批处理；每个 episode 的状态隔离（技能图、历史、MPC 状态按 episode id 隔离）。
- **并发安全**：不同端口可能同时调用；模型 forward 要线程安全/批处理；MPC/CBF 每 episode 独立。
- **延迟守卫**：记录 p50/p95/p99；p99 >400ms 时降 K、跳过 MPC、或返回缓存 chunk；绝不超 180s。
- **soak**：正式计分前跑 30–60 分钟连续请求，检查内存泄漏、端口隔离、超时。
- **回退**：如果共享后端不稳定，退回“每端口一份模型”（需要更多显存）；如果 4-bit 掉点，回 8-bit。

### 4.7 在线循环伪代码

```python
def get_action(obs, episode_state):
    task = parse_task(obs.language)
    graph = episode_state.graph or build_graph(task)
    skill = graph.current_skill()

    # 1) 边界 handoff（仅进入新技能时）
    if graph.just_entered(skill):
        handoff = mpc.plan_to(obs, graph.canonical_start(skill))
        if handoff.feasible:
            return handoff.first_chunk()

    # 2) 技能条件 VLA
    token = skill_token(skill, graph)
    a = vla.act(obs, language=obs.language + token, chunk=16)

    # 3) 测试时候选选择（高风险技能）
    if skill.risk > RISK_THRESHOLD and ttc_enabled:
        candidates = [a] + [vla.act(obs, language=obs.language + token, chunk=16)
                            for _ in range(K - 1)]
        a = flowres_select(candidates, obs, vla)

    # 4) 局部 MPC（刚体桶）
    if skill.mpc_bucket in {"place", "insert", "pull"}:
        a = mpc.refine(obs, a, target=graph.target(skill))
        a = cbf.filter(obs, a, margin=0.03)

    # 5) 接触代理：跟踪误差大 → 减速/后退
    e = tracking_error(obs)
    if e > E1:
        a = slow_down(a, 0.5)
    if e > E2:
        a = back_off(a, 0.02)

    # 6) 执行 + 谓词验证
    episode_state.execute(a)
    if skill.success(obs):
        graph.advance()
    elif skill.failure(obs) or graph.timeout(skill):
        graph.retry_or_fallback()

    return a
```

**注意**：伪代码是“每个 chunk 调一次”，不是每个控制 tick；MPC/CBF 只在 chunk 边界跑，避免高频开销。

## 5. MPC-Lite 设计

### 5.1 状态、动作、模型

| 项 | 选择 | 理由 |
|---|---|---|
| 状态 x | EE 位置 p(3) + rpy(3) + 线速度 v(3) + 角速度 ω(3) = 12D；或双臂关节 q(14D) | EE 空间与 API 的 `ee` 模式对齐；关节空间作为回退 |
| 动作 u | EE 速度/位姿增量，或关节目标增量 | 与 VLA chunk 同空间；底层控制器做 IK |
| 模型 | 双积分/运动学，不含全身动力学 | 最后 5cm 低速，运动学足够；全动力学太贵 |
| 时域 | H=8–16，dt=1/30s | 覆盖 0.27–0.53s；与 chunk 对齐 |
| 约束 | 关节限位、速度/加速度限、桌面平面、容器/目标物/臂杆椭球 | 防撞、防穿桌、防超限 |
| 碰撞体 | 夹爪/腕/前臂 5 个椭球 + 桌面/容器/目标物 | 与 Multi-Link Safety Filtering 一致 [S39] |

### 5.2 代价函数

```text
J = w_p * ||p - p*||²
  + w_r * ||rpy - rpy*||²
  + w_v * ||v||²
  + w_u * ||u||²
  + w_s * ||u_t - u_{t-1}||²
  + w_c * collision_penalty(x)
  + w_t * terminal_cost(x_H, p*, rpy*)
```

- **PLACE**：w_p/w_r 高，w_v 高（接触前低速），terminal_cost 高；
- **INSERT**：w_p/w_r 中高，w_v 中，接触代理触发减速；不做硬力控；
- **PULL**：w_p 中，w_v 低（需要持续拉力），碰撞惩罚高（防带倒其他物体）；
- **REACH/TRANSPORT**：w_c 高（避障），w_p/w_r 中；
- **软体/拉链/液体**：不用 MPC。

### 5.3 求解器与 warm start

- **MPPI**：以 VLA chunk 为均值，采样 N=64–128 条轨迹，rollout 5.1 的模型，按 J 加权；CPU 5–10ms；鲁棒，适合碰撞约束。
- **iLQR**：以 VLA chunk 为初值，3–5 次迭代；CPU 2–5ms；更平滑，适合无复杂障碍的放置。
- **选择**：默认 MPPI；如果 p99 超 20ms 或抖动大，切 iLQR；两者都保留开关。
- **warm start**：VLA chunk 直接作为名义轨迹；MPC 只做局部精修，不重新规划全局；如果 VLA chunk 不可行（碰撞/超限），MPC 用 fallback 直线/圆弧到目标。
- **为什么 warm start 重要**：GPC/warm-start MPC 的证据表明，生成模型 + MPC 精修比单独任一方更可靠、延迟更低 [S37][S38]。

### 5.4 CBF 安全滤波

- **5 椭球**：夹爪、腕、前臂（左右各一）+ 一个冗余/工具椭球；覆盖比 EE 更大的臂段 [S39]。
- **障碍**：桌面、容器、目标物、人类手（如果检测到）；保守 3cm margin。
- **约束**：h(x) = distance(x, obstacle) − margin；ḣ + αh ≥ 0；用 QP 把 u 投影到安全集。
- **性能**：CPU p99 约 2.2ms（Multi-Link 的报告）[S39]；我们目标 <5ms。
- **失败**：QP 不可行 → 停止/后退/重规划；绝不为了完成任务而穿越障碍。
- **注意**：CBF 是安全层，不是任务策略；它不决定“去哪”，只决定“不能去哪”。

### 5.5 接触代理：EE 跟踪误差

没有力/力矩传感器，但可以用 **指令位姿与实际位姿的跟踪误差** 做接触代理：

```text
e_t = ||p_cmd - p_actual|| + λ * ||rpy_cmd - rpy_actual||
```

- e_t 小：自由空间，正常速度；
- e_t > E1（如 5mm/2°）：可能接触/阻力，速度 ×0.5；
- e_t > E2（如 10mm/4°）：可能卡住，后退 2cm，重新对准；
- e_t > E3（如 20mm/8°）：停止，重试/回退；
- 插入时用“小步试探”：1mm 增量 + e_t 监控；不硬推。

**局限**：跟踪误差也受控制器带宽、摩擦、负载影响；必须用调试槽校准阈值，不能直接当力传感器。报告里明确写“接触代理”，不写“力控”。

### 5.6 插入 / 软体 / 拉链分桶

| 桶 | 任务 | 控制 | 验证 | 风险 |
|---|---|---|---|---|
| **刚体放置/堆叠** | T01–T04、T06–T08、T13、T15、T17、T20–T22、T24–T25、T27–T30 | MPC + CBF | 支撑/稳定/关系 | 位姿估计误差 |
| **插入** | T10、T26 | 粗 MPC + 视觉伺服 + 接触代理 | 相对位姿/seated | 无 F/T，成功率有限 |
| **拔出** | T05、T11、T30 | 粗 MPC + 直线拉 | 物体离开/其他未动 | 带倒其他物体 |
| **旋转/闭合** | T07、T09、T12、T14、T17、T28、T29、T31 | VLA + 视觉伺服 | 角度/状态 | 打滑 |
| **拉链** | T18、T19、T23、T31 | VLA + 视觉伺服 | 拉链闭合 | 咬合失败 |
| **软体** | T16 | VLA + 慢速 + 视觉 | 折线/形状 | 形变不可预测 |
| **液体** | T14、T32 | VLA + 视觉伺服 | 液面/目标 | 洒出 |

**原则**：MPC 只进“刚体放置/堆叠/粗插入/拔出”；软体/拉链/液体不碰 MPC。这样既拿到最大收益（19 个刚体任务），又不引入不可控风险。

### 5.7 延迟预算

以 chunk=16、30Hz 为例：chunk 执行时间 = 16/30 ≈ **533ms**。

| 模块 | 预算（p99） | 备注 |
|---|---:|---|
| VLA forward（6B，8-bit） | 150–300ms | 4-bit 可更低；共享后端批处理 |
| TTC（K=4） | 50–150ms | 仅高风险技能；可关 |
| MPC（MPPI/iLQR） | 5–20ms | CPU |
| CBF（5 椭球） | 2–5ms | CPU |
| 谓词/技能图 | <1ms | 确定性代码 |
| **合计** | **< 400ms** | 留 133ms 余量 |

**守卫**：p99 >400ms → 降 K=2 → 关 TTC → 跳过 MPC（只 CBF）→ 返回缓存 chunk。绝不因为推理慢而超 180s。

### 5.8 失效与回退

| 失效 | 检测 | 回退 |
|---|---|---|
| MPC 不可行 | QP/rollout 失败 | VLA chunk + CBF only |
| 位姿估计差 | 跟踪误差大/视觉置信度低 | 关闭 MPC，VLA + 慢速 |
| 技能切分错 | 谓词长期不成立 | 回退任务级 VLA |
| handoff 超时 | >3s | 放弃 handoff，直接执行下一技能 |
| TTC 超时 | p99 >400ms | 关 TTC |
| 4-bit 掉点 | 离线/调试槽 >2pp | 回 8-bit |
| 端口并发冲突 | soak 失败 | 每端口一份模型 |

## 6. 训练配方

### 6.1 训练阶段

| 阶段 | 数据 | 训练 | 目标 | 时间 |
|---|---|---|---|---|
| **A. 技能切分/标注** | 33k episodes + score_steps | 离线 VLM/规则 + DP 对齐 + 10% 抽检 | 12 技能标签、谓词、规范起始/终止位姿 | 1–2 周 |
| **B. 终局技能 SFT** | 终局段 3–5k + 任务级 2k | 冻结 VLM，训动作头 + projector | 先解决“最后一步” | 3–5 天（1×24GB） |
| **C. 全技能 SFT** | 技能均衡 8–12k | 同上 + 技能 token | 中间技能也能条件化 | 5–7 天 |
| **D. 边界扰动** | 回放/合成 1–2k | 同上 + 扰动 | 技能 B 从扰动状态恢复 | 2–3 天 |
| **E. LoRA（可选）** | 8–12k | LoRA on action head / VLM | 只在大改时启用 | 2–4 天 |
| **F. 量化/部署** | — | 8-bit → 4-bit A/B | 延迟/显存 | 2–3 天 |
| **G. 真机调试** | 2 个调试槽 | 谓词/MPC 阈值/延迟 | 发布门 | 按排期 |

**顺序原则**：先 B 后 C；先用终局技能验证“最后一步”假设，再扩展到中间技能。如果 B 在调试槽没有 +5pp 终局提升，停止 C/D，回退到“任务级 VLA + CBF + 谓词”，不继续投入技能图。

### 6.2 数据混合

| 数据 | 比例 | 说明 |
|---|---:|---|
| 终局技能段（PLACE/INSERT/PULL） | 30% | 主假设靶心 |
| 其他技能段 | 30% | 技能均衡，w_s ∝ 1/sqrt(n_s) |
| 任务级完整 episode | 25% | 保留长程/语言/任务上下文 |
| 边界扰动样本 | 10% | 技能 B 从扰动状态开始 |
| 稀有技能过采样 | 5% | ZIP/FOLD/INSERT/PULL 2–3× |
| 正则/回放 | 5% | 防遗忘；可选 |

**每 epoch 8–12k episodes**（250–300GB 子集），不跑 811GB 全量；每 2 epoch 换一次子集，覆盖全部任务。

### 6.3 损失

- **动作损失**：L1 + L2 混合（EE 位置/姿态分开权重）；夹爪 BCE；chunk 内逐步加权（前 4 步权重更高）。
- **技能条件**：不额外加分类损失（token 是输入，不是输出）；如果动作头有辅助技能头，可加 0.1× CE，但默认不加，避免多任务干扰。
- **边界扰动**：与正常 SFT 同样的动作损失；不加“恢复”标签，避免引入额外标注。
- **正则**：weight decay、dropout（技能 token 10–20%）、EMA（可选）。
- **不做**：不训世界模型、不训 reward model、不 RL、不蒸馏第二个模型。

### 6.4 超参数（起点，待调）

| 超参 | 值 | 说明 |
|---|---|---|
| 基座 | WLA-1.0-Base 6B | Apache 2.0 |
| 冻结 | VLM 冻结；动作头/projector 可训 | 官方默认 [S16] |
| 精度 | bf16；8-bit 推理 | 单卡 24GB |
| batch | 8–16（梯度累积） | 视显存 |
| lr | 1e-4（动作头）；1e-5（LoRA） | 余弦/线性 warmup |
| epoch | 3–5 | 早停看验证动作损失 |
| chunk | 16 | 与 API 对齐 |
| 图像 | 224/256 | 4 路；可 resize |
| 历史 | 1–2 帧 | `obs_delta_indices` |
| 技能 token dropout | 10–20% | 保 fallback |
| 种子 | ≥3 | 报告均值/方差 |

### 6.5 算力

- **默认**：1×24GB（4090/3090/A10）可跑冻结 VLM + 动作头；5–10 天/阶段。
- **加速**：4×A100 2–4 天/阶段；只在多阶段并行时值得。
- **存储**：811GB 全量；训练子集 250–300GB；建议本地 SSD/NVMe，避免反复下载。
- **推理**：1×24–48GB 服务 N 端口；8-bit 6B 约 6–7GB 权重 + 激活；4-bit 约 3–4GB。

### 6.6 量化

- 先 8-bit（bitsandbytes/llm-int8 或等价）；离线动作损失掉点 <1pp 才上真机。
- 4-bit 只在 8-bit 稳定后 A/B；掉点 >2pp 就回 8-bit。
- 量化只作用于 VLM/动作头；MPC/CBF 是 CPU float，不受影响。
- 量化后必须重测延迟与动作平滑度；量化可能让 chunk 抖动，需低通/裁剪。

### 6.7 不训练什么（刻意不做）

- 不训 14B WAM/世界模型（DreamZero 路线）[S23]；
- 不从零训 VLA；
- 不 RL/PPO；
- 不训第二个策略做 TTC（用 FlowRes 复用冻结 VLA）[S42]；
- 不训每任务 LoRA；
- 不做大规模域随机化渲染（PGL 降级）；
- 不做全 32 任务高保真孪生（TCLB 只做离线相对比较）。

## 7. 技能图与恢复

### 7.1 运行时状态机

```text
IDLE
  → REACH → [φ: 到位] → GRASP → [φ: 抓住] → LIFT → [φ: 抬起]
  → TRANSPORT → [φ: 到预放] → PLACE → [φ: 稳定/关系]
  → next skill / DONE

任一状态：
  ψ 失败 → RETRY（≤2）→ 仍失败 → RECOVER（回退/重抓/重放）
  超时 → RECOVER → 仍失败 → TASK_FALLBACK（任务级 VLA）
  人为干扰 → PAUSE → 重观测 → 重规划
```

**实现**：一个 episode 一个 `SkillGraph` 对象；包含 `task_id`、`skill_index`、`retry_count`、`start_time`、`predicate_history`、`mpc_state`、`ttc_state`；与端口/模型进程隔离。

### 7.2 谓词实现

- **位姿谓词**：EE/物体位姿与目标比较；阈值按任务校准（1cm/5° 起点）。
- **夹爪谓词**：夹爪闭合值 + 物体随动（视觉跟踪/EE 相对位移）。
- **关系谓词**：on/in/at/inside；用目标容器/支撑面的几何关系 + 视觉分割（轻量）。
- **稳定谓词**：物体在 0.5s 内位移 <5mm；防“放上又倒”。
- **状态谓词**：拉链闭合、盖子闭合、角度变化；用视觉分类/分割或简单几何。
- **未知谓词**：不可观测时标“未知”，不阻塞流程；用 VLA 的隐式判断 + 超时兜底。

### 7.3 重试 / 恢复

| 场景 | 策略 | 上限 |
|---|---|---|
| 抓空 | 重抓（调整 1–2cm/2°） | 2 次 |
| 放置偏移 | MPC 微调/重放 | 2 次 |
| 插入卡住 | 退回 2cm，重对准 | 2 次 |
| 拉链卡住 | 重咬合/回退 | 2 次 |
| 物体掉落 | 重抓/重新开始当前技能 | 2 次 |
| 技能切分错 | 回退任务级 VLA | 1 次 |
| 人为干扰 | 暂停、重观测、重规划 | 不限次数，但计时 |

**总预算**：180s/任务；内部守卫 150s；每个技能有最大时长；重试不叠加超过总预算。

### 7.4 人为干扰反射

- **检测**：外部物体进入工作区、机器人被推、关节速度异常、视觉遮挡。
- **反射**：立即停止/减速（≤200ms），保持当前位姿，重观测；干扰消失后重规划当前技能。
- **不做**：不继续执行原 chunk、不硬推、不把干扰当失败（除非超时）。
- **训练**：NRB 的 human 备注构造“干扰→暂停→恢复”样本；不依赖大规模合成。

### 7.5 NRB：官方 human 备注恢复库

- 官方数据里有人为干扰/失败/重试的 episode；用备注 + 事件检测构造“破坏→恢复”对。
- 训练时把这些对加入 SFT（10% 以内），让模型见过“失败后恢复”，而不是只见过成功轨迹。
- 推理时 SKG 的恢复逻辑是确定性的；NRB 只提升 VLA 在恢复段的行为先验。
- 不做：不把备注当 reward、不训练独立恢复策略。

### 7.6 时间预算

| 任务类型 | 技能数 | 每技能预算 | handoff | 总预算 |
|---|---:|---:|---:|---:|
| 短程（T01/T02/T05/T08/T19/T23/T24/T30/T32） | 2 | 15–25s | 0–1 | 60–90s |
| 中程（T03/T04/T06/T07/T10/T11/T12/T14/T20/T21/T26/T29） | 3 | 15–25s | 1 | 90–120s |
| 长程（T09/T13/T15/T16/T17/T18/T22/T25/T27/T28/T31） | 4–5 | 15–25s | 1–2 | 120–150s |

**守卫**：150s 内部上限；到 140s 仍未完成 → 放弃重试，执行最保守的终局动作（或直接结束），避免 180s 超时。

## 8. 实验矩阵

### 8.1 离线门（不上真机）

| 实验 | 指标 | 通过门 | 失败动作 |
|---|---|---|---|
| 技能切分 | 段级 F1 | >0.85 | 弱技能模式（只终局 token） |
| 动作预测 | 验证集 L1/姿态误差 | 不比任务级差 >10% | 回退任务级 |
| 终局技能 | 终局段成功率（离线分类/回放） | >基线 +10pp | 停止技能图投入 |
| 边界扰动 | 扰动起始的成功率 | >基线 +5pp | 只保留 handoff MPC |
| MPC 回放 | 碰撞率/目标误差 | 碰撞 <5%，误差 <1cm | 调参/关闭 MPC |
| 延迟 | p99 | <400ms | 降 K/关 TTC/量化 |
| 技能 token dropout | 无 token 掉点 | <3pp | 提高 dropout/混合训练 |

### 8.2 调试槽（1 个任务，不计分）

官方调试槽只测 1 个任务、不计分 [S2][S3]。选择：

- **T27 StackBowls**：3 步刚体堆叠，终局 PLACE，最适合验证 MPC/终局假设；
- **T10 PlugCharger**：3 步插入，验证接触代理/插入桶；
- **T31 OrganizePencilCase**：3 步拉链 + 放置，验证“MPC 不该碰软体/拉链”的边界。

每个调试槽跑 **10–20 trials**，记录：成功率、终局步成功率、技能边界成功率、碰撞率、p99 延迟、恢复次数。

### 8.3 计分跑（320 trials）

- 正式提交前至少 1 次全量计分跑；如果预算允许，2 次（不同种子/日期）。
- 记录每个任务 10 次的 success/step score、失败技能、失败谓词、MPC 触发率。
- 用 bootstrap 估计 95% CI；报告均值 ± SE。
- 不做“只挑好任务”的提交；32 任务全跑。

### 8.4 消融矩阵

| ID | 配置 | 目的 | 预期 |
|---|---|---|---|
| A0 | 任务级 WLA 基线 | 基线 | — |
| A1 | + 技能 token | 技能条件收益 | +1–3pp |
| A2 | + 终局技能 SFT | 最后一步收益 | +3–5pp |
| A3 | + MPC-Lite（刚体桶） | 最后 5cm 收益 | +2–4pp |
| A4 | + CBF | 碰撞/干扰鲁棒性 | +1–2pp，碰撞率降 |
| A5 | + BSR handoff | 技能边界收益 | +1–3pp |
| A6 | + 边界扰动训练 | 边界 OOD 收益 | +1–2pp |
| A7 | + TTC（K=2/4） | 测试时选择 | +0–2pp，延迟 +50–150ms |
| A8 | 4-bit vs 8-bit | 成本/掉点 | 掉点 <2pp 才用 |
| A9 | 共享后端 vs 每端口 | 成本/稳定性 | 稳定才用 |
| A10 | 无技能切分（弱技能） | fallback | 不低于 A2 太多 |

**主消融**：A0/A2/A3/A5；其他为工程/增益消融。每个消融至少 3 个种子（离线）或 10–20 trials（调试槽）；计分跑只做最终组合。

### 8.5 诊断指标

- **整任务成功率**（主）；
- **终局步成功率**（机制）；
- **技能边界成功率**（组合）；
- **每技能成功率/重试率**；
- **碰撞率/掉落率/超时率**；
- **MPC 触发率/不可行率**；
- **TTC 选择与最终成功的一致性**；
- **p50/p95/p99 延迟**；
- **每任务 success/step score**（找长尾）；
- **人为干扰恢复率**。

### 8.6 统计功效

| 真实 p | SE（320 trials） | +3pp 的 SE 倍数 | +5pp 的 SE 倍数 |
|---:|---:|---:|---:|
| 0.20 | 2.24pp | 1.34 | 2.23 |
| 0.30 | 2.56pp | 1.17 | 1.95 |
| 0.40 | 2.74pp | 1.09 | 1.82 |
| 0.50 | 2.80pp | 1.07 | 1.79 |

**结论**：+5pp 是“约 2 SE”的最小可信收益；+3pp 需要更多 trials/多轮确认。不要用单次 320 trials 的 +2pp 宣称胜利。

**第二重要**：**I3 + I4**。MPC 负责最后 5cm，handoff 负责技能边界；两者合起来才是“技能组合”的闭环。单独 I3 只能救刚体终局，单独 I4 只能救边界；合起来才能覆盖长程任务。

**第三重要**：**I1 + I2**。技能图 + 技能 token 是把“32 个任务”压成“12 个技能”的低成本结构；没有它，MPC/handoff 不知道“现在该做什么”。

## 11. 风险、合规与开关

### 11.1 单模型合规（最高风险）

官方原文：“所有任务须基于同一模型完成，不得混合使用多个模型一起进行测试，但对模型类型不作限制（World Model、VLA 均可）。” [S2][S3]

**我们的解释**：

- SVC 是唯一**学习模型**（一个 checkpoint）；
- SKG 是**确定性状态机/代码**，不是按任务切换的模型；
- MPC-Lite/CBF 是**确定性控制器**，不含学习参数；
- TTC 复用**同一个冻结 VLA**，不引入第二个模型；
- OPT 是**统计表**；NRB 是**训练数据**。

**风险**：组委会可能把“VLA + MPC”视为两个模型，或把“技能图”视为手工任务策略。**缓解**：

1. 模型卡明确写“one learned checkpoint + deterministic controller”；
2. 发邮件 `challenge_support@unitree.com` 书面确认（模板见下）；
3. 准备 **纯 VLA fallback**：关闭 MPC/handoff/TTC，只保留 CBF + 谓词；如果被拒，直接提交 fallback；
4. 不按任务切模型、不按任务切 LoRA、不做任务分类器路由。

**邮件模板（中文）**：

```text
主题：关于通才赛道“单模型”定义的确认

您好，

我们计划提交一个基于 WLA-1.0-Base 微调的单 checkpoint 模型，完成全部 32 个任务。
推理时，该模型输出动作 chunk；此外我们使用：
1) 一个确定性的技能状态机（由官方 score_steps 生成，不含学习参数）；
2) 一个确定性的局部 MPC/安全滤波（不含学习参数，仅做最后 5cm 的位姿精修与避障）。

请问这种“一个学习模型 + 确定性控制器”的组合是否满足“所有任务须基于同一模型完成，不得混合使用多个模型”的要求？
我们不会按任务切换模型，也不会为不同任务使用不同 checkpoint。

谢谢！
```

**如果回复“不允许”**：关闭 MPC/handoff/TTC，只保留 CBF + 谓词 + 技能 token；主假设降级为“终局技能 SFT + 技能条件”，仍可能 +3–5pp。

## 13. 开放问题

### 13.1 问组委会（按优先级）

1. **单模型边界**：一个学习 checkpoint + 确定性 MPC/CBF/技能图，是否合规？（§11.1 模板）
2. **N 的具体值**：正式评测用几台 G1/Dex1？是否允许共享后端？
3. **控制频率**：API 的动作频率是多少？是否与数据 30fps 一致？
4. **步骤分聚合**：32 任务的总平均步骤分是“任务均值的均值”，还是按步数加权？tie-break 具体怎么算？
5. **外部数据**：是否允许使用公开外部数据/预训练权重？WLA-1.0-Base 是否算官方允许的基座？
6. **测试时选择**：同一 checkpoint 生成 K 个候选再选一个，是否算“多个模型”？
7. **调试槽**：每个队伍有多少调试槽？是否只能测 1 个任务？能否反复测？
8. **失败重试**：单次 180s 内，技能重试/恢复是否允许？是否有次数限制？
9. **人类干扰**：`human_1`/`human_4` 的具体脚本是什么？是否可检测/暂停？
10. **未见物体**：`unseen_object_3` 是“训练集外物体”还是“新类别”？是否提供物体清单？

### 13.2 自己实测（按优先级）

1. **控制频率/延迟**：调试槽实测 API tick、VLA forward、MPC/CBF 延迟；
2. **技能切分 F1**：抽 200 段人工标注，算段级/边界 F1；
3. **终局提升**：T27 调试槽 A0 vs A2，10–20 trials；
4. **MPC 碰撞/抖动**：回放 + 调试槽，碰撞率/跟踪误差；
5. **handoff 收益**：T27/T10 长程，A2 vs A5；
6. **量化掉点**：8-bit/4-bit 离线动作损失 + 调试槽；
7. **共享后端 soak**：30–60 分钟，N=3/更多端口；
8. **真实榜单**：等官方上线后，用真实头部数据校准“<30%”先验。

- 全 32 任务高保真孪生；
- 大规模 RL/世界模型训练；
- 每任务 LoRA/多模型路由；
- 全量 26 万段检索；
- 自采外部数据；
- 五指灵巧手（官方 API 当前主要二指夹爪）。

## 14. 一句话押注

**把“全局语义”留给一个已对齐的 6B 基座，把“技能边界”交给公开评分步骤生成的技能图，把“最后 5 厘米”交给确定性的局部 MPC 与安全滤波——这是本轮最低成本、最贴合“成功率优先 + 单模型”规则、也最可能把榜首从 30% 往上推的路线。**

> 如果只能记一件事：**不要训练一个更大的世界模型去救最后一步；用一个确定性的局部世界模型/MPC 去救最后一步。**
