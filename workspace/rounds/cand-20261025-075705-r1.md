# 第 8 轮 · CONTACT：碰撞是信号，数据集是课程，动力学是监督

> 检索/复核日期：2026-10-25（UTC）。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型、选手自部署 + 官方远程真机评测。本轮三个灵感词是「碰撞检测」「数据集构建」「动力学」。状态文件已到第 7 轮，本轮按第 8 轮续写。

## 0. 先纠偏：六个会改变判断的事实

### 0.1 排名是“成功率优先”，不是“成功率 + 步骤分综合”

官方手册写得很清楚：排行榜按**平均成功率从高到低**排序；成功率相同才看**步骤分**；再相同则**先提交者优先**。每个任务跑 10 次，5 个泛化轴（位置/干扰物/背景/未见物体/人类干扰）各 2 次，共 320 次；单次上限 180s。

这直接修正第 7 轮的一个隐含假设：第 7 轮把“终局放置约占 60% 步骤分”当成主杠杆，但步骤分只是 tiebreak。**部分完成不能替代成功；为了步骤分牺牲成功率是负期望。** 终局放置仍然重要，因为它是成功闸门；但它重要在“把任务做完”，不在“多拿步骤分”。本轮所有组件的第一目标因此改成：**提高完整任务成功率**，步骤分只作为同分时的第二目标。

### 0.2 榜单仍是占位，“榜首不到 30%”无法核实

`leaderboard.html` 仍是“即将发布 / Coming Soon”；`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，8 个模型、256 条 task_metrics 都是脚本生成的占位，最高平均成功率 **29.7%**（MolmoAct2 / DexHacker）。`runs.html` 同样是 256/256 占位。

所以：**“榜首不到 30%”是占位数字，不是真实榜首。** 它可以当“如果真实榜首也在这个量级”的保守情景，但不能当事实，更不能用来推断“只要 +3pp 就能赢”。本轮只把它当压力测试：如果真实榜首是 30%，+5~8pp 是数量级跃迁；如果真实榜首是 60%，+5pp 仍是显著进步。两种情景下结论方向一致，只是赔率不同。

### 0.3 接触约束不是少数任务：21/32 的终局都靠接触

按官方 32 任务描述做粗分类：

| 类型 | 任务 | 数量 | 终局关键 |
|---|---|---:|---|
| A 插入/力约束 | T05 拔网线、T09 锁工具箱、T10 插充电器、T12 翻锁环、T26 插网线、T32 注射器 | 6 | 对位、插入深度、卡扣/摩擦 |
| B 铰接/闭合 | T17 合笔盒、T18 拉书包链、T19 拉拉链、T23 合球拍包、T28 合耳机盒、T29 合盒盖、T31 合笔袋拉链 | 7 | 抓滑块、沿轨拉动、闭合到位 |
| C 接触主导放置/变形 | T07 摆正相框、T11 取电池、T14 倒药、T16 叠毛巾、T20 叠纸杯、T21 摆盘、T25 放杯架、T27 叠碗 | 8 | 稳定接触、释放、堆叠/变形 |
| D 以抓放为主 | T01、T02、T03、T04、T06、T08、T13、T15、T22、T24、T30 | 11 | 抓取接触 + 放置 |

A+B+C = **21/32**，对应 210/320 次计分 trial。若这 21 个任务的完整成功率 +10pp，总成功率约 +6.6pp；+15pp 则约 +9.8pp（算术，不是实测）。D 类也含抓取接触，但终局更偏位姿；本轮不把它们当主战场。

### 0.4 没有力/力矩/触觉：接触只能“推断”，不能“测量”

提交接口的公开观测只有：4 路 RGB、双臂关节/EE 位姿、夹爪、下半身、单个语言字符串；数据集的 state/action 也没有力、力矩、触觉字段。`control_space` 只有 joint / ee 两种位置级动作，没有刚度/力指令。

这条约束很硬，直接判死了三类 2026 年很热的方法在本赛道的“原样使用”：

- **CompVLA**（`arXiv:2609.23614`）联合预测运动 + 刚度矩阵，需要阻抗控制接口；我们没有刚度输出。
- **TacVLA**（`arXiv:2603.12665`）依赖触觉 token 和接触门控；我们没有触觉。
- **Opt2VLA**（`arXiv:2609.23968`）在 VLA-to-control 接口显式输出力参考，依赖力矩跟踪控制器；我们没有力/力矩观测与指令。

**结论：本赛道的接触感知必须是“视觉 + 本体 + 几何”的推断，而不是力/触觉测量。** 这既是限制，也是差异点：谁能在无 force/tactile 的接口里把接触做稳，谁就拿到别人复制不了的收益。

### 0.5 `action` 不是未来命令：离线“跟踪误差”不能拿来标接触

我在 StackBowls 的 127,239 个连续 transition 上核对了 `action.*_ee_pose_gripper_base` 与 `observation.state.*_ee_pose_gripper_base`：

- `||action_t.xyz − state_t.xyz||` 中位数 **1.28–1.47cm**，且差异主要在 z 轴（约 +1.0~1.2cm）；
- `||action_t.xyz − state_{t+1}.xyz||` 中位数 **1.20–1.35cm**，并不比“对同刻 state”更小；
- `action` 差分与 `state` 差分的相关系数约 **−0.76~−0.79**，符合“action ≈ state + 固定工具偏移”的模式，而不是“action 是未来目标”。

所以：**至少 StackBowls 上不能用 action−state 残差离线标注“跟踪误差/接触”。** 那个残差主要是一个固定坐标系/工具偏移，不是控制误差。离线接触标签必须来自物体响应（跟踪、光流、相对运动）、夹爪事件、轨迹拐点、立体几何。运行时我们有自己的命令，`command − next_state` 才是有效跟踪误差；这是线上信号，不是离线标签。

### 0.6 WLA 的输入是 3 视图，但 API 给了 4 路：右高相机可以专门做几何

WLA-1.0 的 Unitree 配置 `unitree_img_with_stereo` 用 `head_stereo_left_rec` + `wrist_left` + `wrist_right` 三路；`unitree_img_wo_stereo` 用 `head_stereo_left` + 两路腕部。API 则给 `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路。

这不是障碍，反而是一个干净的分工：**策略仍吃 3 路（左高 + 两腕），右高只用于立体深度/点云/碰撞盾，不强行塞进 WLA 的视觉编码器。** 这样不破坏底座输入分布，又能在推理侧得到 metric 几何。若以后要加第四路，再加一个小 adapter，不作为本轮主线。

### 0.7 手册仍未读全：外部数据/预训练权重规则未知

公开手册在 **2.2 比赛资源** 后截断；外部数据、预训练权重、单模型审计边界都未读到。本轮默认：**只使用官方 33k + Apache-2.0 的 WLA-1.0-Base**；仿真/自采数据挂在合规开关后，默认 OFF。所有“数据构建”先设计成“对官方数据做标签/挖掘”，而不是“引入外部数据”。

## 1. 三个灵感词，各自钉到官方事实上

### 1.1 碰撞检测：不只是安全，还是“接触事件探测器”和“难例生成器”

碰撞检测在本方案里有三个作用，按重要性排序：

1. **事件信号**：机器人连杆/夹持物体与场景点云的最近距离从大变小、再配合夹爪闭合/物体运动，能把轨迹切成 approach → contact → manipulate → release 四段。接触相位是 SSG 步骤图里最缺的标签。
2. **安全兜底**：候选动作块在立体点云 + 机器人 capsule 上做 swept-volume 检查；预测会撞就换块/抬升/后退。它不依赖学习，不会把“碰撞”学成“风格”。
3. **难例生成**：在仿真里对接触窗口做 ±1–3cm / ±5–10° 的动作扰动，记录“撞/不撞、成功/失败”，得到同一状态下不同动作的反事实对。这是训练动力学头最值钱的数据。

证据：SafeLoop（`arXiv:2609.26313`）用视觉+本体训练风险预测器，输出身体碰撞/物体失败的概率与 time-to-hazard，在 24 个 LIBERO 任务 + 3 个真机任务上把 hazard cases 降约 70%，同时保持任务成功率。它证明“接触/碰撞风险可以从视觉+本体预测”；但它是**外部 wrapper + 独立风险模型**，不符合本赛道单模型要求。我们的做法是：**把风险头并进 WLA 的同一个 checkpoint，把 rollback 换成接触状态机里的确定性恢复原语。**

### 1.2 数据集构建：33k 成功演示是“偏置数据”，缺的是接触边界

官方 33k 演示几乎都是成功轨迹。成功轨迹告诉我们“接触应该长什么样”，但不告诉我们“碰撞、卡住、滑落、被挪走长什么样”。如果只在成功数据上加一个 contact head，它学到的只是“接触通常发生在这些位置”，不是“什么动作会导致失败”。

所以本轮的数据构建不是“再采更多数据”，而是**把已有数据变成接触课程**：

- **ContactBank（正样本）**：从每条演示里挖 grasp / insert / articulate / release / settle 窗口，配物体跟踪、相对位姿、夹爪事件、步骤相位。
- **Near-contact（边界样本）**：接触前 0.5s、释放后 0.5s、距离阈值附近；这些窗口最能区分“快到了”和“已经接触”。
- **Counterfactual Contact Data（难负样本）**：仿真里对同一状态做动作/物体/释放高度扰动，记录碰撞与结果；用 AD-WM（`arXiv:2609.30264`）的教训——**factual prediction error 低不代表能区分动作**，所以必须构造同一状态下的反事实对，而不是只做下一帧预测。
- **Disturbance pairs（人类干扰）**：官方 human 备注是现成剧本（移物、撤销、拔起、拉上再拉开）；构造“干扰→检测→恢复”对，训练/评测接触状态机的恢复分支。

旁证：
- “Data and Learning Where it Matters”（`arXiv:2607.15982`）只在接触段自主采 2–2.5h 数据，四个真机长程任务平均 96%，端到端基线 37%，力降低 49%，场景级 OOD 仍 90%。**这支持“接触段的数据密度比全局数据量更重要”。**
- QoQ（`arXiv:2603.09056`）用 influence function 选高质量演示；PhyVisGen（`arXiv:2609.25653`）用 IPC 做软接触、合成数据训练的策略在五个真机任务 65–95%；ARSTAG（`arXiv:2609.24563`）从单图+语言生成 Real2Sim2Real 数据，pi0.5 真机 74.6%。这些说明“接触数据可以工程化构造”，但也提醒合成数据的物理/视觉保真度是瓶颈。
- Contact-Anchored Retargeting（`arXiv:2609.24093`）指出：跨手型保留的是**接触结构**（哪些手指区域接触哪些物体位置、顺序），不是关节运动。对我们：接触标签应锚在“物体/夹爪的接触关系”，不是“关节轨迹”。

### 1.3 动力学：要学“动作→物体运动”，不是“下一帧视频”

接触失败的本质是动力学预测错：以为还能往下压，其实已经卡住；以为松手会落稳，其实会滚；以为拉链在动，其实滑块没抓住。一个像素级视频世界模型能表达这些，但推理太贵；本赛道 180s/任务、30Hz 接口，视频生成不现实。

本轮选择**紧凑的物体中心动力学**：

- 输入：当前多视图 + 本体 + 语言 + 候选动作块；
- 输出：未来 0.5–1s 的对象关键点/区域位移（刚性物体可加 SE(3)），以及接触状态/稳定性；
- 监督：演示里的物体跟踪 + 仿真反事实；
- 推理：一个 forward 里的轻量 head，不生成视频；用预测的物体运动给候选 chunk 打分。

证据：
- MotionWeave（`arXiv:2609.39324`）用动作诱导的运动定位 + 时序运动残差，在六个 MetaWorld 任务 75.3%，比 π0 高 8.6pp，尤其在持续交互任务；说明“动作条件的运动表征”比“整体未来视觉”更贴近控制。
- Streaming-WAM（`arXiv:2609.28927`）和 Rolling-WAM（`arXiv:2609.30247`）说明世界动作模型可以异步/滚动降延迟，但仍以视频生成为核心；我们不跟这条重路线。
- OASIS（`arXiv:2605.25829`）把中间表征对齐到 SE(3) EE 轨迹，说明几何对齐的表征对 OOD 有帮助；我们的动力学头进一步对齐到**物体**运动，而不只是 EE。
- AD-WM（`arXiv:2609.30264`）在 OGBench-Cube 上把 hard-start 从 3.7% 提到 52.0%，并指出 factual error 与闭环 success 排序不一致；这直接支持“用反事实/动作判别训练动力学”，而不是只做下一帧回归。

## 2. 本轮主判断：从“放在哪”到“接触怎么演化”

### 2.1 第 7 轮解决了“where”，第 8 轮要解决“how”

第 7 轮的 PILOT-GPR 是有效的：SSG 把评分步骤变成状态机，PGL/OPT 把“放在哪”变成槽位→锚点→6D 位姿，SVL 做落点校验。但它默认“到了目标位姿，剩下就是松手”。在 21/32 的接触任务里，最后 1–3cm 不是位姿问题，而是**接触演化**问题：

- 插头：对位对了，但角度差 2°、压入方向不对，会卡住；
- 拉链：抓到布而不是滑块，拉得再准也不闭合；
- 叠碗：第二个碗放上去时碰了第一个，整摞倒；
- 倒药：瓶口对准了，但倾角/速度不对，药撒了；
- 注射器：针头对位了，但推杆/液面/阻力没建模；
- 人类干扰：物体被挪 5cm，策略还在执行旧轨迹。

所以本轮不是推翻第 7 轮，而是给它补上**接触层**：PGL/OPT 给目标，CDR 负责“怎么碰、什么时候松、碰坏了怎么退”。

### 2.2 一个更锋利的失败分类

| 失败 | 典型任务 | 现有 layer 为什么不够 | 本轮对策 |
|---|---|---|---|
| C1 碰撞/碰倒 | T20/T21/T25/T27 | 位姿对了，但接近路径/夹持物体扫到已放置物 | 立体碰撞盾 + 扫掠体积检查 |
| C2 插入卡住/压不进 | T05/T10/T12/T26/T32 | 位置到了，但没有“压入/停顿/回退”的接触策略 | 接触头 + 动力学头 + 力代理（stall） |
| C3 铰接/拉链抓错 | T17/T18/T19/T23/T28/T29/T31 | 视觉上像抓住了，实际抓的是布/边缘 | 接触类型头 + 物体相对运动校验 |
| C4 变形/倾倒动力学 | T07/T14/T16 | 刚体位姿模型不适用 | 物体关键点/区域动力学 + 稳定性头 |
| C5 释放/滑落/未到位 | 全部放置类 | 松手就结束，没有 settle 验证 | 稳定性头 + SVL 2.0 |
| C6 人类干扰/撤销 | human 轴全部 | 开环执行，不检测“世界变了” | 残差监测 + 接触状态机回滚 |
| C7 透明/遮挡 | T14/T19/T27/T32 | 深度/跟踪失效 | 置信度门控 + 腕部近景 + 保守恢复 |
| C8 干扰物碰撞 | clutter 轴 | 路径规划不管场景点云 | 碰撞盾 + 候选 chunk 拒绝 |

C1–C5 是“接触动力学”问题，C6 是“接触事件归因”问题，C7–C8 是“接触感知可靠性”问题。它们共享同一套底层：**接触状态 + 物体运动 + 几何距离**。

### 2.3 算术：为什么值得把主火力放这里

- 21/32 任务、210/320 trials 含显著接触约束；
- 若接触层让这 21 个任务的完整成功率 +10pp → 总成功率约 +6.6pp；
- +15pp → 约 +9.8pp；
- human 轴单独 64 trials；检测/恢复 +30pp → 该轴 +30pp，总 +6pp 的 1/5 ≈ +1.2pp；
- 碰撞盾若把“碰撞导致的失败”减半，在接触任务里再贡献几个 pp。

这些是**算术上界情景**，不是承诺；但它们说明：接触层的杠杆足够大，值得用一轮去赌。反过来，如果调试槽里 T27/T10 的终局成功率提升 <5pp，说明接触假设不成立，应回退到第 7 轮的放置层 + 纯碰撞盾。

### 2.4 与第 7 轮的关系：不是重启，是换主攻

- **保留**：SSG（步骤图/状态机）、PGL（槽位→锚点）、OPT（少样本位姿迁移）、SVL（落点校验）、NRB（官方备注恢复）、WLA 底座、TLE/ACP/GF 数据引擎、DebugLoop、合规开关。
- **升级**：SVL → 接触感知的 settle/recover；NRB → 干扰检测数据；TLE → 接触事件/物体跟踪标签。
- **降级**：ICR（检索上下文）从“主线”降为“可选加速”；L2L（产学研）从“数据农场”降为“规则明确后的备选”；步骤分从“第二目标”降为“tiebreak 诊断”。
- **新增**：CEM（Contact Event Miner）、CCD（Counterfactual Contact Data）、CDR heads（Contact/Dynamics/Stability）、GCS（Geometric Collision Shield）、CSM（Contact State Machine）、CART（Contact-Aware Reranking/Trigger）。
- **修剪**：外力/触觉方法（接口不支持）、外部风险 wrapper（单模型不允许）、RL specialists（多模型）、全视频世界模型（延迟/算力）、全任务高保真孪生、每任务 LoRA。

## 3. 方案轮廓：CDR-WLA

```text
    ├─ CCD：Isaac Lab 动作/物体/释放高度扰动 + 2.5D 编辑

    ├─ 干扰对：官方 human 备注剧本 → 移物/撤销/拔起/拉开 → 恢复段
    └─ CDR heads：Contact / Object-Dynamics / Stability（与 action expert 同一 checkpoint）

  4 路 RGB + 本体 + 语言
    ├─ 策略：WLA 3 视图（左高 + 两腕）→ 候选 chunk
    ├─ GCS：右高立体点云 + 机器人 capsule + 夹持物 → 扫掠碰撞检查
    ├─ CDR：接触概率/类型、物体运动、释放稳定性 → 给 chunk 打分
    ├─ CSM：APPROACH → CONTACT → MANIPULATE → RELEASE → VERIFY
    └─ 恢复：retreat / lift / re-align / regrasp / re-place / replan
```

一句话：**用“接触事件”把 33k 成功演示切成课程，用“反事实接触数据”教动力学，用“碰撞盾 + 接触状态机”在推理时兜底；所有学习组件仍在一个 WLA checkpoint 里。**

### 3.1 为什么不是 SafeLoop / CompVLA / TacVLA / RouteRLT

| 方法 | 为什么不能原样用 | 我们借什么 |
|---|---|---|
| SafeLoop | 外部 wrapper + 独立风险模型，违反单模型 | 风险可从视觉+本体预测；rollback 有效 |
| CompVLA | 需要刚度矩阵/阻抗控制接口 | 用“减速/回退/重对准”近似柔顺，不输出刚度 |
| TacVLA | 需要触觉 | 用立体距离/物体响应替代触觉门控 |
| Opt2VLA | 需要力参考/力矩跟踪 | 用 stall/跟踪误差做“力代理”，不声称力控 |
| RouteRLT | VLA + RL specialists 多模型 handoff | 用同一 checkpoint 的 phase-aware heads 替代 handoff |
| Streaming/Rolling-WAM | 视频生成重、延迟高 | 只学紧凑物体动力学，不生成像素 |

## 1. 事实核对与纠偏（本轮新增，来源见 §12）

### 1.1 排序规则：成功率优先，步骤分只做 tiebreak

官方手册（中文/英文两版）明确：

- 每个任务 **10 次 trial**，5 个泛化轴（位置/干扰物/背景/未见物体/人类干扰）各 **2 次**；32 任务共 **320 次**；
- 单次 **180s**；
- 排行榜按**平均成功率从高到低**排序；
- 成功率相同 → 比**步骤分**；
- 再相同 → **先提交者优先**；
- 必须**单一模型**完成全部 32 任务；
- 另有**不计分单任务调试**通道，需预约，管理员确认。

**纠偏**：第 7 轮把“终局放置约占 60% 步骤分”当成主杠杆；步骤分确实重要，但只是 tiebreak。**部分完成不能替代成功。** 本轮把“完整任务成功率”作为唯一主目标，步骤分只用于诊断“失败发生在哪一步”。

### 1.2 榜单仍是占位：“榜首不到 30%”不可核实

- `leaderboard.html` 仍是「即将发布 / Coming Soon」；
- `leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`；
- 8 个模型、256 条 task_metrics 是脚本生成；最高平均成功率 **29.7%**（MolmoAct2 / DexHacker）；
- `runs.html` 是 256/256 占位，详情页写“测试视频占位”。

**纠偏**：29.7% 是占位数字。用户所说的“榜首不到 30%”目前无法核实。本报告只把它当保守情景，不当前提；如果真实榜首是 60%，接触层的收益仍然成立，只是赔率不同。

### 1.3 数据与接口：没有力/力矩/触觉

- 数据集：32 任务、约 33k episodes、169h；四路相机（`head_stereo_left/right` + `wrist_left/right`）、30fps；`meta/tasks.parquet` 里每条指令有 5 条英文复述（`@` 分隔）；state/action 含双臂关节、EE 位姿（base/torso）、夹爪、下半身；**没有力、力矩、触觉字段**。
- 提交接口：4 路 RGB（`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`）、双臂关节、夹爪、下半身、单个 `observation.language`；`control_space` 只有 `joint` / `ee`；**没有力/力矩/触觉观测，也没有刚度/力指令**。

**推论**：CompVLA、TacVLA、Opt2VLA 这类依赖刚度/触觉/力参考的方法不能原样使用；接触必须从视觉、本体、几何推断。

### 1.4 `action` 不是未来命令：离线 action−state 残差不能标接触

在 `G1_Dex1_StackBowls`（979 episodes / 295,609 帧 / 30fps）的 **127,239** 个连续 transition 上核对：

| 量 | 左臂 | 右臂 |
|---|---:|---:|
| `L2(action_t.xyz − state_t.xyz)` 中位数 | 1.28cm | 1.47cm |
| `L2(action_t.xyz − state_{t+1}.xyz)` 中位数 | 1.20cm | 1.35cm |
| 差异主方向 | z ≈ +1.03cm | z ≈ +1.14cm |
| `action` 差分 vs `state` 差分相关 | −0.76 | −0.79 |

`action_t` 与 `state_{t+1}` 并不比与 `state_t` 更近；差分相关为负且接近“同一常量偏移”的预期。**结论：至少 StackBowls 的 action 更像“带固定工具/坐标系偏移的同刻状态记录”，不是下一时刻的命令。** 因此：

- 不能用 `action−state` 离线标注“跟踪误差/接触/碰撞”；
- 离线接触标签必须来自物体跟踪、光流、夹爪事件、轨迹拐点、立体距离；
- 运行时我们发出自己的 command，`command−next_state` 才是有效跟踪误差，可用于 stall/接触检测。

这条负结果直接决定了 CEM 的设计（§4.1），也是本轮最重要的“不要做什么”。

### 1.5 WLA 输入是 3 视图，API 给了 4 路

WLA 的 Unitree 配置：

- `unitree_img_with_stereo`：`head_stereo_left_rec` + `wrist_left` + `wrist_right`；
- `unitree_img_wo_stereo`：`head_stereo_left` + `wrist_left` + `wrist_right`。

API 给 4 路：左右高位 + 左右腕部。**策略仍吃 3 路（左高 + 两腕），右高专用于立体深度/点云/碰撞盾**；不破坏底座输入分布，又能拿到 metric 几何。若未来要加第四路，加一个小 adapter，不作为本轮主线。

### 2.3 算术：接触层的上界

```text
接触任务 = 21 / 32
接触 trials = 21 × 10 = 210 / 320

若接触任务完整成功率 +10pp:
  全局增益 = 0.10 × 210/320 = +6.6pp
若 +15pp:
  全局增益 = 0.15 × 210/320 = +9.8pp

human 轴 = 64 trials（32 任务 × 2）
若检测/恢复让 human 轴 +30pp:
  全局增益 = 0.30 × 64/320 = +6.0pp 的 1/5 = +1.2pp
```

这是算术上界，不是承诺；真实增益取决于接触层是否真的解决 C1–C6。若真实榜首是 30%，+6.6pp 是数量级跃迁；若真实榜首是 60%，+6.6pp 仍是显著进步。

### 2.4 时间预算

- 官方 180s/trial；演示中位数约 6–10s/任务，长程 15–30s；
- 接触层新增：GCS <10ms/步、CDR heads <5ms/步、CART 只在近接触时 K=2–4；
- 恢复预算：每步 ≤2 次，总恢复 ≤20s；长程任务（T16/T17/T31）≤1 次/步；
- 最坏情况仍应留 ≥30s 余量，避免超时。

## 3. CDR-WLA 架构

### 3.1 总览

```text
┌──────────────────────── Offline ────────────────────────┐
│ 官方 33k（LeRobot v3, 4 相机, state/action, 5 复述）      │
│   ├─ CEM：夹爪事件 + 轨迹拐点 + 物体跟踪 + 立体距离       │
│   │     → ContactBank（grasp/insert/articulate/release）  │
│   ├─ CCD：Isaac Lab 动作/物体/释放扰动 + 2.5D 编辑        │
│   │     → 同状态反事实对（撞/不撞、稳/不稳）              │
│   ├─ Disturbance：官方 human 备注剧本 → 干扰/撤销/恢复     │
│   └─ CDR heads：Contact / Object-Dynamics / Stability     │
│         与 WLA action expert 同一 checkpoint              │
└──────────────────────────────────────────────────────────┘
                            │
┌──────────────────────── Inference ──────────────────────┐
│ 4 RGB + proprio + language                               │
│   ├─ policy：WLA 3 视图（左高+两腕）→ K 个候选 chunk      │
│   ├─ GCS：右高立体点云 + 机器人 capsule + 夹持物          │
│   ├─ CDR：接触概率/类型、物体运动、释放稳定性             │
│   ├─ CART：近接触时对 K 个 chunk 打分/重排                │
│   ├─ CSM：APPROACH→CONTACT→MANIPULATE→RELEASE→VERIFY     │
│   └─ 恢复：retreat/lift/re-align/regrasp/re-place/replan  │
└──────────────────────────────────────────────────────────┘
```

### 3.2 主干：WLA-1.0-Base + 三个轻量头

- WLA-1.0-Base：6B、Apache-2.0、约 2500h 真机数据、64 任务；动作专家可微调，VLM 可冻结或 LoRA。
- 训练只更新 action expert + CDR heads（VLM 默认冻结）；CDR heads 是 2–3 层 MLP/交叉注意力，参数量 <1% 主干。
- 推理一个 forward 产出 action chunk + contact/dynamics/stability；没有第二个模型。

**为什么不是世界模型？** 视频世界模型（WMA-0、Streaming-WAM、Rolling-WAM）能表达接触，但生成像素的延迟/算力不适合 30Hz 闭环；本方案只学“动作→物体运动”的紧凑量，训练和推理都便宜。

### 3.3 CDR heads

#### (a) ContactHead：接触状态 + 类型

- 输入：action expert 的 horizon hidden states + 视觉 token + proprio + step embedding；
- 输出：每个未来 step 的 4 类状态 `{none, stable_contact, impact/collision, slip}` + 6 类类型 `{grasp, push, insert, articulate, release, none}`；
- 监督：CEM 标签（高置信度）+ 仿真标签；
- 用途：CSM 状态转移、CART 风险项、恢复触发。

#### (b) ObjectDynamicsHead：物体中心运动

- 输入：视觉 token + EE/夹爪状态 + 候选 action chunk；
- 输出：未来 horizons `{5, 10, 15, 30}` 的物体位移（2D 关键点/区域；刚性物体加 SE(3)）；用 1–2 个 learned object query 关注“被操作物/目标容器”；
- 监督：CEM 的物体跟踪（CoTracker/TAPIR + 立体深度）；仿真真值；
- 用途：判断“动作是否真的推动了物体”、插入是否前进、释放后是否稳定；CART 的动力学一致性项。

#### (c) StabilityHead：释放稳定性

- 输入：当前视觉/proprio + 计划释放位姿 + 物体动力学表征；
- 输出：释放后 0.5s 稳定的概率；
- 监督：演示终端释放窗口（正）+ 仿真释放高度/时机扰动（负）；
- 用途：决定“现在松手还是再降 5mm/再对齐一次”。

#### (d) 反事实对比损失（ADL）

只做下一帧回归会学到“动作无关”的动力学。AD-WM 的教训是：factual error 低不代表能区分动作。因此加：

```text
L_ADL = -log exp(-||d(s,a+) - d_obs||/τ)
          / Σ_{a- ∈ A-} exp(-||d(s,a-) - d_obs||/τ)
```

其中 `a+` 是实际执行的动作块，`a-` 是仿真里同一状态的扰动动作块，`d` 是动力学头输出，`d_obs` 是观测到的物体运动。只在有反事实对时启用；真实数据只做正样本回归。

### 3.4 接触状态机（CSM）

```text
APPROACH ──(p_contact>0.6 或 d_min<1cm)──► CONTACT
CONTACT  ──(稳定接触 3 帧)──────────────► MANIPULATE
MANIPULATE ─(SSG 终局/插入到位)─────────► RELEASE
RELEASE  ──(夹爪打开)───────────────────► VERIFY
VERIFY   ──(0.5s 稳定 + 谓词保持)───────► DONE
VERIFY   ──(不稳定/谓词回退)────────────► RECOVER
任意状态 ─(impact/slip/外部事件)────────► RECOVER
RECOVER  ──(修复成功)───────────────────► APPROACH/CONTACT/MANIPULATE
```

- 双阈值 + 滞回，避免接触概率抖动导致状态机抖动；
- `d_min` 来自 GCS；`p_contact` 来自 ContactHead；
- `impact`：ContactHead 的 impact 类 + GCS 距离突降 + 关节跟踪误差突增；
- `slip`：夹爪闭合但物体相对 EE 位移 > 阈值；
- `外部事件`：物体运动与机器人动作残差大，且机器人不在接触；见 §6.4。

### 3.5 几何碰撞盾（GCS）

**输入**：

- 右高/左高立体（若为同步立体对；W1 验证）→ 去畸变、校正、SGBM/RAFT-Stereo → 深度 → 点云（base 系）；
- 机器人 URDF → 连杆 capsule；关节状态 → FK；
- 夹持物：夹爪开度 + 腕部视觉外接球/胶囊；
- 候选 chunk → EE 轨迹（EE 控制）或关节轨迹 FK（joint 控制）。

**检查**：

1. 点云降采样到 2–5k 点，剔除桌面/已知支撑面，KD-tree；
2. 候选轨迹采样 10–20 个中间位姿，做 swept-volume；
3. 每个 capsule 到点云的最近距离 `d_min`；
4. `d_min < 3cm` 警告、`<1cm` 否决；阈值按任务容差标定；
5. 若夹持物与场景距离 < 物体半径 + margin，同样否决。

**动作**：

- 减速/抬升/旋转/换候选 chunk；
- 全部候选被否决 → `retreat` + `replan`；
- 透明/反光导致深度空洞 → 标记 `unknown`，降低 GCS 权重，交给 ContactHead + 保守 margin。

**为什么可行**：WLA 训练已用立体左目；API 给右高；相机安装固定；`state_d435` 可做外参校准。GCS 是确定性代码，不引入第二个学习模型。

### 3.6 接触感知重排（CART）

默认 K=1；仅在以下条件采样 K=2–4 个候选 chunk（不同噪声种子/模式）：

```text
p_contact > 0.4  或  d_min < 5cm  或  StabilityHead < 0.6
```

评分：

```text
S(chunk) = w1 * progress
         - w2 * P(collision)
         - w3 * P(slip)
         - w4 * ||dyn_pred - dyn_nominal||
         - w5 * (1 - P(stable))
```

- `progress` 来自 SSG 步骤/谓词头或 ContactHead 的“推进”表征；
- 选最高分；若全部低于阈值 → 不执行，进入 `retreat/replan`；
- 只在近接触时增加算力，正常段仍 1 个 chunk，控制 p99。

### 3.7 恢复原语

| 原语 | 作用 | 触发 |
|---|---|---|
| `retreat(d)` | 沿接近方向后退 3cm | 碰撞/卡住/impact |
| `lift(d)` | 抬升 5cm | 夹持物刮到场景 |
| `re-align` | 腕部视觉伺服重新居中/对角度 | 插入偏、抓偏 |
| `regrasp` | 开爪→后退→重新抓 | slip/抓错 |
| `re-place` | 重新拿起→放到目标 | 释放失败/倒了 |
| `replan` | 更新 SSG/物体位置，重跑策略 | 外部干扰/谓词回退 |

预算：每步 ≤2 次；总恢复 ≤20s；长程任务 ≤1 次/步。恢复后必须重新过 CSM 的接触检查，不能直接跳回原动作。

## 4. 数据引擎：CEM + CCD

### 4.1 CEM：Contact Event Miner

**目标**：把 33k 成功演示切成“接触课程”，而不是随机采样帧。

**管线**：

1. **同步**：LeRobot v3 读 4 路视频、state、action、语言；30fps；按 episode 对齐。
2. **机器人运动学**：FK 得 EE/连杆位姿；计算速度、加速度、jerk；夹爪开度及一阶差分。
3. **物体跟踪**：
   - 离线用 SAM2 分割 + CoTracker/TAPIR 跟踪关键点；
   - 刚性物体可选 FoundationPose 得 6D；变形物体用关键点/稠密光流；
   - 立体深度给 metric 尺度；腕部近景补遮挡。
4. **候选接触事件**：
   - 夹爪闭合/打开事件；
   - EE 速度骤降/方向突变（Savitzky-Golay 平滑后的拐点）；
   - 物体运动起始/停止，且与 EE 运动相关；
   - 机器人 capsule 与物体点云最近距离 < 阈值；
   - 任务相位（SSG 步骤边界）。
5. **接触分类**（规则 + 轻量分类器）：
   - grasp：夹爪闭合 + 物体随 EE 动；
   - push：夹爪开 + 物体被推离；
   - insert：近距离 + 物体低速 + EE 继续前进/ stall；
   - articulate：夹爪闭合 + 物体局部旋转/滑动；
   - release：夹爪打开 + 物体下落/稳定；
   - collide：物体/机器人加速度异常 + 位移突增（成功演示里也会有近碰撞）；
   - slip：夹爪闭合但物体相对 EE 位移。
6. **窗口化**：每个事件取前 0.5s + 后 1.0s（30–45 帧），配物体 track、相对位姿、夹爪、相位、任务 ID、语言复述。
7. **置信度**：跟踪失败/深度空洞/多物体混淆 → 低置信度，不入训练集，只做诊断。
8. **人工审计**：抽 500 窗口，双人标注；目标 precision ≥0.85、recall ≥0.80；不达标就改规则/阈值。

**规模估算**：

- 33k episodes；抽 20% = 6.6k episodes；
- 每条 3–5 个接触窗口 → 20k–33k 窗口；
- 每窗口 30–45 帧 → 0.6M–1.5M 帧，约占全量 10M 帧的 6–15%；
- 训练时接触窗口过采样 3×，近接触 2×，普通帧 1×；避免接触任务把抓放能力挤掉。

### 4.2 标签定义

| 标签 | 取值 | 来源 |
|---|---|---|
| `c_t` 接触状态 | 0 none / 1 stable / 2 impact / 3 slip | CEM + 仿真 |
| `k_t` 接触类型 | grasp / push / insert / articulate / release / none | CEM 规则 + 审计 |
| `d_t` 物体运动 | 关键点 2D 位移 / 刚性 SE(3) | 跟踪 + 立体 |
| `s_t` 释放稳定性 | 0/1 | 释放后 0.5s 位移 + 谓词 |
| `h_t` 外部干扰 | 0/1 + move/remove/undo | 官方备注 + 残差 |
| `collision` | 0/1 + severity | GCS/仿真 |

**注意**：不要把 `action−state` 残差当标签（§1.4）；不要把“夹爪闭合”直接当“抓住”——闭合但没抓住是 C3 的主要失败。

### 4.3 CCD：Counterfactual Contact Data

**目标**：给动力学头/接触头提供“同一状态、不同动作”的反事实对，而不是只给成功轨迹。

**生成方式**：

| 方式 | 做法 | 标签 | 用途 |
|---|---|---|---|
| 动作扰动 | 在接触窗口，对下一 chunk 加 ±1–3cm / ±5–10° 扰动，Isaac Lab 重放 1–2s | 撞/不撞、成功/失败、接触类型 | ADL 反事实对；ContactHead 负例 |
| 物体扰动 | 目标/容器平移 1–5cm、旋转 ±10° | 成功/失败、碰撞 | 鲁棒性；干扰检测 |
| 释放扰动 | 释放高度 +0.5/1/2cm、提前/延后 0.2s | 稳定/滑落/弹跳 | StabilityHead 负例 |
| 干扰物 | 在接近路径旁放一个新物体 | 碰撞/绕开 | GCS/CART 负例 |
| 2.5D 编辑 | 真实图像里移动物体 + 深度/补全 | 只做视觉鲁棒性 | 不用于接触标签 |

**规模**：

- 8–12 个接触任务 × 100 episodes × 2–3 扰动 ≈ 2k–3.6k episodes；
- 只取接触窗口前后 1–2s，不生成完整长程；
- 合成数据 ≤ 真实数据的 30%；若规则不允许仿真，CCD 关闭，退回“只用真实 ContactBank + 几何盾”。

**过滤**：

- 物理可行性：穿模/爆炸/非因果 → 丢弃；
- 视觉一致性：渲染与真实差异过大 → 丢弃或只用于动力学头；
- 结果平衡：撞/不撞、稳/不稳各占 40–60%，避免全负例；
- 人工抽检 10%。

### 4.4 干扰对（Disturbance pairs）

官方 human 备注是现成剧本：T27 叠了第二个后拿走第二个、T19 拉上后拉开、T14 拧开后再拧回、T10 拔起插头、T17 合上后打开、T24 物品快到了放回起点、T12 中途把锁拿走、T02/T04/T11/T25 移动水果/盘子/底座。

**做法**：

- 用备注在仿真/2.5D 里构造干扰事件，时间点放在对应步骤前后；
- 标签：`h_t=1`、类型（move/remove/undo）、干扰后物体位姿；
- 训练：ContactHead 增加“外部事件”类；残差监测器用这些对校准阈值；
- 恢复：不训练专门的恢复专家；由 CSM 触发 `replan`，让基础策略在新观测下重跑；脚本原语只做兜底。
- 评测：human 轴用这些剧本做压力测试，统计检测延迟/恢复成功率。

**为什么不做 RL 恢复专家**：本赛道单模型；RouteRLT 式的 VLA + RL specialists 虽然有效（物理插接 65.7% vs 8.6%），但多模型 handoff 不符合“单一模型”要求。我们把“专家”压成同一 checkpoint 的 phase-aware head + 确定性原语。

## 5. 训练配方

### 5.1 损失

```text
L = L_flow
  + λ1 L_contact
  + λ2 L_dyn
  + λ3 L_stab
  + λ4 L_ADL
  + λ5 L_calib
  + λ6 L_step        # SSG 谓词，沿用第 7 轮
  + λ7 L_anchor      # PGL 锚点，沿用第 7 轮
```

| 项 | 含义 | 起始权重 |
|---|---|---:|

| L_stab | 释放稳定性 BCE | 0.1 |
| L_ADL | 反事实对比（仅仿真对） | 0.05 |
| L_calib | 温度/置信度校准（ECE） | 0.01 |
| L_step | SSG 谓词 BCE | 0.2 |
| L_anchor | 锚点/位姿一致性 | 0.1 |

训练时对低置信度标签做 mask；接触/近接触窗口加权；不要让 L_dyn 在背景/机器人区域回传（用物体 mask）。

### 5.2 课程

| 阶段 | 数据 | 目标 | 退出条件 |
|---|---|---|---|
| 0 | 官方 33k | 复现 WLA 基线 | held-out 不降 |

| 5 | +CART/CSM（推理） | 闭环 | 仿真碰撞 −30% |
| 6 | +干扰对 | 外部事件 | 检测 recall ≥0.8 |
| 7 | 全量 + 量化/蒸馏 | 延迟 | p99 <150ms |

### 5.3 超参

- WLA-1.0-Base 6B；VLM 冻结；action expert 全量或 LoRA（rank 64/alpha 128）；

- 最小可运行版：不做 CCD/重训，只做 CEM 诊断 + GCS + CSM（CPU/单卡），先验证碰撞盾和状态机。

## 6. 推理

### 6.1 伪代码

```python
def act(obs, ssg, csm):
    views = three_views(obs)                 # left_high + wrists
    pc    = stereo_pointcloud(obs.left_high, obs.right_high)
    cands = policy.sample(views, obs.proprio, obs.language, k=1)

    if near_contact(obs, pc) or csm.risk_high:
        cands = policy.sample(..., k=4)

    scored = []
    for chunk in cands:
        d_min, hit = gcs.check(pc, obs.joints, chunk, held_object)
        contact = cdr.contact(chunk, views, obs.proprio)
        dyn     = cdr.dynamics(chunk, views, obs.proprio)
        stab    = cdr.stability(chunk, views, obs.proprio)
        if hit and d_min < VETO:
            continue
        scored.append((score(chunk, contact, dyn, stab, d_min), chunk))

    if not scored:
        return recover("retreat_replan")

    chunk = max(scored).chunk
    send(chunk)
    csm.update(contact, d_min, obs)
    return chunk
```

### 6.2 阈值与校准

- 接触概率/稳定性温度缩放；目标 ECE <0.05；
- `p_contact` 阈值按任务校准：插入/拉链偏低（早进入 CONTACT），抓放偏高（避免误触发）；
- `d_min`：警告 3cm、否决 1cm；透明任务放宽到 0.5cm 并降权；
- stall：`||command−next_state||` 连续 3 帧 > 阈值，且 `p_contact>0.5`；
- 外部事件：见 §6.4；
- 所有阈值写入配置，调试槽可调，不硬编码在模型里。

### 6.3 延迟

| 项 | 目标 |
|---|---:|
| WLA forward（3 视图，chunk 30） | 60–100ms |
| CDR heads | <5ms |
| GCS（2–5k 点，10–20 采样） | <10ms |
| CART K=4 | 4× policy forward；仅近接触 |
| 端到端 p99 | <150ms |

若 p99 超标：降 K、降点云、缓存视觉 token、只在 contact 风险高时跑 CART。

### 6.4 外部干扰检测

```text
r_t = observed_object_flow - predicted_object_flow
若 ||r_t|| > τ_r 连续 2 帧，且机器人不在接触：
    → 外部事件（human/distractor）
若 SSG 谓词 1→0：
    → undo
若目标物体在视野中消失：
    → re-localize；找不到则 abort/replan
```

- 用 CUSUM/双阈值降误报；
- 触发后：暂停 → 重新定位 → 更新 SSG → `replan`；
- 不假设干扰只发生一次；每次检测都重新规划；
- 恢复预算与 §3.7 一致。

## 7. 实验矩阵

### 7.1 假设

| ID | 假设 | 判定 |
|---|---|---|
| H1 | CEM 能以 ≥0.85 precision 挖出接触窗口 | 500 窗口审计 |
| H2 | CDR heads 提升接触/动力学/稳定性离线指标 | F1/ADE/AUC |
| H3 | GCS 降低碰撞率且不降成功率 | 仿真 + 调试槽 |
| H4 | CART 在近接触时提升成功率 | 消融 K/开关 |
| H5 | 干扰监测 recall ≥0.8、误报 <10% | 官方备注剧本 |
| H6 | 接触层让 21 个接触任务 +10pp | 调试槽/计分跑 |
| H7 | 接触层不伤 11 个抓放任务 | 分任务回归 |

### 7.2 离线

- 接触 F1（状态/类型）、混淆矩阵；
- 物体运动 ADE@0.5s / SE(3) 误差；
- 稳定性 AUC / Brier；
- 反事实排序准确率（ADL）；
- GCS 碰撞预测 precision/recall（仿真真值）；
- 外部事件检测延迟/误报（备注剧本）。

### 7.3 仿真

- Isaac Lab，12 个接触任务 × 50 trials；
- 指标：成功率、碰撞率、near-miss、恢复成功率、完成时间、穿透深度（力代理）；
- 扰动：动作噪声、物体偏移、干扰物、释放高度；
- 只做相对比较，不用仿真绝对成功率选模型。

### 7.4 真机

- 调试槽：T27（叠碗）、T10（插充电器）、T19 或 T26（拉链/网线）；每个 10 trials；
- 指标：完整成功率、碰撞次数、接触失败类型、恢复成功率、耗时；
- 计分跑：320 trials；分任务/分轴统计；
- 每次大版本最多 1 个调试槽；先预约再训练。

### 7.5 消融

| 消融 | 目的 |
|---|---|
| 无 ContactHead | 接触状态是否必要 |
| 无 DynamicsHead | 动力学是否必要 |
| 无 StabilityHead | 释放判断是否必要 |
| 无 ADL | 反事实对比是否必要 |
| 无 GCS | 几何盾贡献 |
| 无 CART | 重排贡献 |
| 无 CSM | 状态机贡献 |
| 无 CCD | 仿真数据贡献 |
| K∈{1,2,4} | 测试时算力 |
| margin∈{1,2,3}cm | 保守度 |
| 立体 vs 单目 | 几何收益 |
| 接触过采样 3× vs 1× | 数据权重 |

### 7.6 基线

- B0：WLA-1.0-Base fine-tune；
- B1：B0 + 第 7 轮 PILOT（SSG/PGL/OPT/SVL）；
- B2：B1 + GCS；
- B3：B2 + CEM/CDR（无 CCD）；
- B4：B3 + CCD/ADL；
- B5：B4 + CART/CSM/恢复；
- 参考（不合规，仅对照）：SafeLoop 外部风险 wrapper、RouteRLT specialists、CompVLA/TacVLA/Opt2VLA（接口不支持）。

### 7.7 统计

- 320 trials；若 p≈0.3，SE≈2.56pp；+5pp 约 2σ；
- 配对 bootstrap（按任务/种子）；报告 95% CI；
- 分任务 10 trials 噪声大，不单独下结论；看 21 任务聚合 + 分轴；
- 预注册主指标：完整成功率；次指标：碰撞率、恢复率、步骤分（tiebreak 诊断）。

## 8. 创新点清单（持续迭代；动机/差异/可行性/资源/步骤/风险/状态）

> 状态：押注=本轮主线；保留=沿用；升级=旧点改造；降级=保留但非主线；砍=不做。

### I1 CEM / ContactBank（新增，押注）
- 动机：33k 成功演示缺接触边界；接触是 21/32 终局关键；离线 action−state 残差不可用。
- 差异：不是“随机采样帧”，而是以夹爪事件/轨迹拐点/物体响应/立体距离切接触窗口；标签锚在接触关系，不是关节轨迹。
- 可行性：数据字段齐；SAM2/CoTracker 离线可用；StackBowls 可做 pilot。
- 资源：8×H100 3–5 天；500 窗口人工审计；存储约 1–2TB。
- 步骤：StackBowls pilot → 8 任务 → 32 任务 → 审计 → 版本化。
- 风险：透明/遮挡跟踪失败 → 低置信度不入库；标签噪声 → 审计 + co-teaching。
- 状态：押注。

### I2 CCD 反事实接触数据（新增，押注）
- 动机：只学成功轨迹会学到“动作无关”的动力学；需要同状态不同动作的反事实。
- 差异：不是随机仿真数据，而是围绕接触窗口的动作/物体/释放扰动，配 ADL 对。
- 可行性：Unitree Isaac Lab 有 G1/Dex1 资产；官方动作可重放；2k–3.6k episodes 可控。
- 资源：8×H100 约 1 周；仿真工程 2 人周。
- 步骤：动作扰动 → 物体/释放扰动 → 过滤/平衡 → 训练 → 消融。
- 风险：sim-to-real gap → 合成 ≤30%；规则不允许 → 默认 OFF。
- 状态：押注（合规开关后）。

### I3 CDR heads（新增，押注）
- 动机：接触状态、物体动力学、释放稳定性是 21/32 终局的共同缺口；现有 VLA 只输出动作。
- 差异：三个轻量头并在 WLA 同一 checkpoint；不引入外部模型；不生成视频。
- 可行性：WLA action expert 可微调；heads <1% 参数；单卡可跑最小版。
- 资源：8×H100 2–3 周；标注/审计 1 人月。
- 步骤：ContactHead → DynamicsHead → StabilityHead → 联合训练 → 校准。
- 风险：辅助损失拖累动作 → 权重 warmup/早停；标签噪声 → mask/审计。
- 状态：押注。

### I4 GCS 立体几何碰撞盾（新增，押注）
- 动机：C1/C8 碰撞是终局失败和 clutter 轴的直接原因；学习模型无法保证不撞。
- 差异：确定性几何 + swept volume；右高专用于深度；不改变 WLA 输入。
- 可行性：URDF/FK/点云都是现成；CPU <10ms；API 有左右高相机（需 W1 验证同步/基线）。
- 资源：1 人周工程 + 标定；无需训练。
- 步骤：标定 → 点云 → capsule → 扫掠 → 阈值 → 调试槽。
- 风险：透明深度空洞 → 置信度门控；过于保守 → 软 margin + 只否决近碰撞。
- 状态：押注。

### I5 CSM + CART + 恢复（新增，押注）
- 动机：接触是阶段性的；不同阶段需要不同策略；松手后要验证。
- 差异：把接触状态机、候选重排、恢复原语接成闭环；不是单一策略端到端。
- 可行性：状态机/原语是确定性代码；CART 复用 CDR；不改接口。
- 资源：2 人周；调试槽 2–3 次。
- 步骤：状态机 → 重排 → 恢复原语 → 预算守卫 → 真机。
- 风险：误报/抖动 → 双阈值 + 滞回；耗时 → 预算守卫。
- 状态：押注。

### I6 干扰检测/恢复（升级 NRB/SVL，押注）
- 动机：human 轴是 1/5 trials；官方备注是现成剧本；开环执行无法发现世界变化。
- 差异：从“恢复库”升级为“检测→归因→重规划”；不训练 RL specialist。
- 可行性：备注已公开；残差监测用现有预测；恢复用基础策略重跑。
- 资源：1–2 人周；仿真/2.5D 数据。
- 步骤：备注剧本 → 干扰对 → 检测阈值 → 恢复接 CSM → 评测。
- 风险：误报 → CUSUM/双阈值；物体被拿走无法恢复 → 标记 abort，不硬撑。
- 状态：押注。

### I7 ADL 反事实对比损失（新增，中优先）
- 动机：AD-WM 证明 factual error 与闭环 success 排序不一致；动力学头必须能区分动作。
- 差异：在动力学头上加 InfoNCE 式反事实对比，只在仿真对上启用。
- 可行性：CCD 提供正/负对；实现简单。
- 资源：无额外数据；训练 +10%。
- 步骤：对构造 → 损失 → 消融。
- 风险：负例太简单 → 难负例挖掘；仿真偏差 → 只在辅助损失。
- 状态：中优先。

### I8 SSG 评分步骤图（保留，底座）
- 动机：官方步骤/权重公开；成功=全步骤；相位标签给 CEM/CSM。
- 差异：本轮不承担主增益，只做相位骨架和步骤谓词。
- 可行性：确定性代码 + 谓词头；32×5 复述可匹配。
- 风险：谓词噪声 → 演示统计校准。

### I9 PGL + OPT（保留，底座）
- 动机：解决“放在哪”；给接触层提供目标位姿/容器系。
- 差异：不再单独承担成功率；与 CDR 组合。
- 风险：透明容器位姿失败 → 分桶回退。

### I10 SVL 2.0（升级）
- 动机：释放后要验证稳定；接触层提供稳定性头。
- 差异：从“位移+谓词”升级为“稳定性头 + 接触状态 + 恢复”。
- 风险：耗时 → 预算。

### I11 ICR 检索（降级/可选）
- 动机：少样本上下文仍可能有用；但延迟/复杂度高。
- 差异：不作为主线；只在长程任务做相位先验。
- 风险：p99 超标 → 关。

### I12 L2L 产学研（暂缓）
- 动机：背景/位置多样性；但规则未明，且接触数据比背景更缺。
- 差异：从“数据农场”降为“规则明确后的备选”。
- 风险：外部数据违规 → 默认 OFF。

### I13 DebugLoop（保留）

### I14 WLA/GPR 主干（保留）

## 13. 开放问题

1. 公开手册 2.3 之后是否允许仿真数据、自采数据、外部预训练权重？单模型审计边界是什么？
2. 真实榜单何时发布？真实榜首/分布是多少？（当前 29.7% 只是占位。）
3. 不计分单任务调试的可用次数/成本/是否随机化泛化条件？
4. 左右高相机的基线/同步/标定参数是否固定？能否稳定得到 metric 深度？
5. 透明/反光物体（药瓶、拉链、纸杯）立体深度可用性如何？是否需要腕部单目兜底？
6. human 备注的编号含义（轴/试次）？干扰后物体是否归还？是否只干扰一次？
7. 排名聚合：每任务平均成功率再平均，还是按 trial 汇总？步骤分公式？
8. 接口是否隐藏提供关节电流/力矩（即使不在公开 schema）？若提供，接触检测会更强。
9. 是否允许在 180s 内做多候选 chunk 的测试时算力（CART K=4）？有无隐藏计算限制？
10. 评测语言是英文 5 复述之一、中文，还是未见复述？CDR 是否对语言变化敏感？
11. 离线打标签用的 SAM2/CoTracker/FoundationPose 是否算“外部模型”？若审计严格，能否换经典光流/跟踪？
12. 仿真资产（G1/Dex1/物体）与官方真机的视觉/物理差距有多大？CCD 的负迁移风险需要多快暴露？
