# 第 1 轮（本轮灵感：「人机协作」×「常识推理」；承接 UniBot-SAGE 基线）

> **基线承接声明**：本轮沿用状态文件中已核实的 UniBot 线事实，以及 UniBot-SAGE 的 P0 组件（IP-02 抓握确认、IP-03 chunk 缝合、IP-06 代理评测），不重复其推导。本轮只回答两个新灵感带来的**增量问题**：任务级完成判据从哪来、人类作为意图性干扰源该如何建模。新增编号 U13–U20 / L8–L12 / E619–E632；旧编号继续有效。

## 0. 一句话

把策略从"会动的开环执行器"升级为**知道什么算做完、并且知道旁边有人**的任务级闭环系统：**常识校验器**负责判定完成/违反前置条件，**人机协作层**负责让行、恢复，并从人类示范的纠错片段中学习恢复。

## 1. 直觉：两个灵感的第一性原理

### 1.1 常识推理：VLA 缺的不是知识，是"可检查的完成判据"

操作任务的本质是一个**带前置条件的偏序**：先抓后抬、先对齐后插入、先开盖后倒。VLA 从成功轨迹里学的是"下一步看起来像什么"，不是"现在是否已经完成、是否违反物理常识"。这在最后一环最危险——它可能已经放好还在继续推，或者根本没抓住却一路执行到超时。

因此常识推理的正确用法不是把它写进 prompt 让模型"更聪明"，而是把它**外化成可执行判据**：

- **完成判据**：物体是否进入容器 / 是否插入 / 是否解锁 / 是否在目标位姿；
- **前置条件**：是否抓住、是否对齐、容器是否打开；
- **可行性约束**：单自由度夹爪不能拧盖、捏线，必须换非抓取原语；
- **失败解释**：指出违反了哪条常识，供恢复策略使用。

这直接补上一轮的最大风险：抓握漏判会把"可救失败"变成"硬失败"；有了任务级 verifier，"没完成"可以被更早发现并触发重试/改抓，而不是等超时。

### 1.2 人机协作：人是会主动改变场景的智能体，不是像素噪声

5 类泛化中的"人为干扰"不是随机视觉扰动，而是**有意图的、非平稳的转移**。域随机化假设"扰动与任务无关"，但人会直接把目标拿走、把手伸进工作区、把已放好的物体碰倒。正确建模不是"更鲁棒的视觉"，而是：

- **检测**：人手/人体进入工作区、目标被移动；
- **意图**：人手朝哪个物体去、是否与机器人目标冲突；
- **协调**：冲突时让行（yield）、被改场景后从当前状态恢复（resume）、不与人抢；
- **利用协作痕迹**：遥操作里的"人类纠错"片段（反向、重抓、停顿后再来）是最后一步失败的最佳监督信号，比只学成功轨迹更接近评测要考的"恢复"。

### 1.3 合成：在低层闭环之上加任务级闭环

上一轮的三层栈是**低层接地（抓握）→ 技能路由 → 推理期适应**。本轮在其上加一条**任务级闭环**：

**常识任务模型 G（子目标 + 前置条件 + 完成判据）→ verifier V（每 0.5–1 s 或相位切换时判定）→ 控制器（continue / hold / retry / replan / stop）**，

并在旁边挂一个**人机协作层 HALO（检测人 → 预测意图 → 让行/恢复）**。关键工程约束：V 与 HALO 都**默认关闭、零开销**，只在触发时介入，保证不伤害基线（延续上一轮退化链思想）。

## 2. 上一轮遗留、被两个灵感直接命中的三个缺口

1. **任务级闭环缺失**：上一轮只有抓握的低层闭环，没有"任务是否完成"的判定；榜单只给终态成功，等于没有稠密信号。
2. **人为干扰被当成普通偏移**：上一轮 IP-04 的上下文调制是统计式的，无法处理"人把目标拿走"这种意图性事件。
3. **人类示范只被当成功轨迹**：遥操作里的纠错/重试片段被丢弃，而那正是最后一步恢复的稀缺监督。

## 3. 新瓶颈的可量化视角（不引入新外部数据，只用可测代理量）

| 代理量 | 定义 | 预注册判据 | 推出的设计 |
|---|---|---|---|
| 人为干扰权重 | 5 类泛化等权时，该类收益占总分 1/5 | 若该类基线显著低于总均值 | HALO 的边际收益可高于"32 任务普遍 +0.5 分" |
| 完成后自毁率 `post_success_regression` | 首次视觉完成之后物体状态又偏离目标的比例 | >5% ⇒ stop-on-success 纯收益；<1% ⇒ 该杠杆可忽略 | TLC 的 stop 分支 |
| 纠错片段 prevalence | 速度反向 + 重抓 + 停顿后动作定义的 recovery segment 占比 | <3% ⇒ 降级为小样本微调，不做主线 | IP-11 |
| 常识相似度 ↔ 性能相似度 | 任务图/常识嵌入距离与模型性能向量距离的秩相关 | Spearman ≥0.3 ⇒ 语义路由可用 | IP-13 |

## 4. 研究问题

- **Q6（完成判据的可校准性）**：在只有 RGB + 本体状态的接口下，能否把"任务完成 / 子目标完成"估成**带校准**的判据，并做到高精度（假完成率低）？
- **Q7（verifier-in-the-loop 的净收益）**：用 V 触发 stop/retry/replan，能否在不降低基线的前提下，修复"完成后自毁"与"漏抓超时"？
- **Q8（人机协作的建模边界）**：把人为干扰建成意图性事件（检测→意图→让行→恢复）是否优于把它当视觉域随机化？收益是否集中在人为干扰 split？
- **Q9（人类纠错的可迁移性）**：遥操作中的纠错片段能否训练出可迁移的恢复策略，而不是过拟合到具体物体？
- **Q10（常识约束与技能路由的结合）**：用任务图/常识嵌入做任务相似度，是否比纯语言嵌入的路由更能兑现上一轮 oracle +4.26 上界？

## 5. 设计原则（在 P1–P6 之上新增）

- **P7 判据优先于提示**：常识必须以可执行判据（V）或约束（原语掩码）进入系统，不允许只写在 prompt 里。
- **P8 非对称门控**：V 的"完成"判定必须高精度；宁可晚停，不可早停。verifier 触发的动作只能是**安全动作**（停/慢/重观察/重试），不能直接覆盖策略的高频输出。
- **P9 人机协作默认零开销**：没有检测到人时 HALO 完全不介入；检测到冲突时才让行；恢复必须从当前观测重建，不依赖被污染的历史。
- **P10 单 checkpoint 内实现**：verifier 与 HALO 都做成共享主干上的头/轻模块，保持"单模型、单 API"合规（若被质疑，退化到 head-only 版本）。

## 6. 合成架构：UniBot-CARE

- **底层（沿用）**：GraspVerify 抓握隐变量 + ChunkStitch + 通用 VLA。
- **任务层（新）**：Commonsense Task Model G + Verifier V + Task-Level Controller（TLC）。
- **协作层（新）**：HALO（Human detection → intent → yield/resume）。
- **数据层（新）**：Recovery Mining（从遥操作中挖纠错片段）+ 人为干扰增强（人手/目标移动的合成与真机采集）。
- **工程层（沿用）**：延迟、端口隔离、审计；新增 V 的低频调度预算。

**退化链新增**：

- V 不可用/低置信 ⇒ 退回无任务级闭环的基线（保留抓握闭环）；
- HALO 误检 ⇒ 默认不介入，仅当人手进入安全距离且持续 N 帧才触发；
- 恢复策略不可用 ⇒ 退回"停在安全位 + 继续原策略"。

## 7. 与上一轮 IP 的合并与剪枝

- **保留/强化**：IP-02（抓握是 V 的物理子判据）、IP-03、IP-06（代理评测是验证 V/HALO 的唯一内部标尺）。
- **合并**：IP-04 的上下文调制并入 HALO 的"场景状态"；IP-01 的任务路由增加常识嵌入（Q10）。
- **降级**：IP-05（pivot）、IP-07（双空间）暂缓，因为它们不直接提高终态完成判据的可靠性。
- **新增**：IP-09 CTM/Verifier、IP-10 HALO、IP-11 Recovery Mining、IP-12 TLC（verifier-in-the-loop）、IP-13 Semantic Router。

## 8. 本轮最大风险

**一句话**：整套新杠杆压在"常识完成判据"上，而 verifier 的**假完成**会让机器人在任务其实没完成时提前停手——这个错误在"未见物品"和"人为干扰"两类最需要它的场景里恰恰最容易被触发，且一旦发生就是零分而非扣分的硬失败。

## 9. 下一轮迭代计划

- **深化**：把 V 从"单帧判定"升级为"带时序的证据累积"（多帧 + 动作前后对比），并与人手意图预测共享特征；把 TLC 的 stop/retry/replan 做成可学习的风险敏感决策。
- **剪枝**：若 `post_success_regression <1%` 且 Q7 无净收益 ⇒ 砍掉 TLC 的 stop 分支，只保留 retry；若 HALO 在人为干扰 split 上 <+3 分 ⇒ 降级为"安全让行"规则，不做意图预测。
- **保留项**：IP-09 与 IP-12 在任何情况下不砍（它们是任务级闭环的骨架）。

## 0. 本轮结论摘要

**一句话路线**：在 UniBot-SAGE 的"低层接地 + 技能路由 + 推理期适应"之上，加一条**任务级闭环**——常识任务模型给出可检查的完成判据，verifier 低频判定，控制器只在**安全动作**集合内决策（stop / hold / retry / replan）；再加一条**人机协作层**——检测人 → 预测意图 → 让行/恢复，并从遥操作纠错片段训练恢复头。

**为什么是这两个启发（三条设计依据）**：

| 依据 | 形式 | 推论 |
|---|---|---|
| 5 类泛化等权时，人为干扰占 1/5 | 该类收益按 1/5 折算进总分 | HALO 的期望收益可量化，且集中在单一 split |
| 任务可写成带前置条件的偏序 | 子目标图 `G` | 常识可外化为 verifier 与约束，而非 prompt |
| 终态成功是唯一计分货币（上一轮 L1） | `step ≈ 1.337·succ + 0.09` | 判据必须直接服务于"最后一环被完成" |

**核心赌注**：榜单只给终态成功 ⇒ "能判定完成/未完成"本身就是一种被所有人忽略的**控制信号**。它不是诊断工具，而是控制原语。

## 2. 创新点详述

### IP-09 · CTM-Verifier 常识任务模型 + 完成判据（P0）

- **动机**：VLA 会动，但没有可检查的完成判据。评测只给终态成功，导致策略无法知道自己是否已经完成；这在最后一环表现为两种硬失败：完成后继续动作而自毁、未完成却一路执行到超时。
- **与现有方案的差异**：现有做法是把语言指令直接喂给 VLA，让"常识"隐式存在于权重里。我们把常识**显式拆成结构**：
  - `G = (V_g, ≺, Pre, Eff, C)`：子目标集合、偏序、前置条件、效果、完成判据；
  - `V(o, ℓ, G) → (p_done, p_sub, violation)`：完成概率、各子目标概率、违反的条件；
  - 结构由人工模板（32 任务各一份）+ VLM 自动实例化（物体名、容器名、关系）得到，允许 OOD 落到通用模板。
- **技术可行性**：中–高。①VLM 已经具备"物体是否在容器里/是否插入/是否盖着"的语义能力；②几何检查（bbox 包含、支撑关系、夹爪闭合、末端-物体相对位移）提供低成本、可解释的证据；③把 V 做成**共享主干上的头**，避免"第二个模型"的合规问题。
- **所需资源**：数据 = 官方 32 数据集（用于模板实例化与校准）+ 自建少量失败/恢复 rollout；算力 = 共享主干 + 轻头，单卡数小时；接口 = 无新增字段（仍是单 `get_action`）。
- **落地步骤**：
  1. 为 32 任务写任务图模板（子目标 + 前置条件 + 完成判据），人工抽检；
  2. 用 VLM 在离线帧上批量实例化 `C`（物体/容器/关系）；
  3. 训练/校准 `V` 头：主任务 = 子目标完成二分类，辅助 = 违反条件多标签；
  4. 做**可靠性图**与分场景校准（见 L9：OOD 下 PPV 会塌，必须分场景阈值）；
  5. 低频调度：每 `K` 步或相位切换时调用，其余步用轻量证据累积。
- **风险**：①假完成（false success）是最硬的风险 —— 见 P8 与 L8/L9；②任务图模板写错会把策略引向错误子目标 ⇒ 模板只约束"检查什么"，不约束"怎么动"；③VLM 延迟 ⇒ 低频 + 蒸馏小头。

### IP-10 · HALO 人机协作层（P0）

- **动机**："人为干扰"是 5 类泛化之一，而且是**意图性**事件：人会拿走目标、把手伸进工作区、碰倒已放好的物体。域随机化无法覆盖"社会性"转移。
- **与现有方案的差异**：不做"更鲁棒的视觉"，而是把人类建成**显式状态** `h_t`（是否在场、手的位置/速度、被操作物体、预测目标、与机器人目标是否冲突），并定义一个**协调决策**：
  - `continue`：人不在冲突区；
  - `yield`：人手进入安全距离且目标冲突 ⇒ 减速、后退、保持夹持、等待；
  - `resume`：人离开或目标被移动 ⇒ 从当前观测重新定位目标、重建任务图状态、继续；
  - `handover-ready`（若任务含递交）：保持物体稳定、等待人类取走。
- **技术可行性**：中。①人手检测可用轻量检测器（公开手部数据 + 腕部/头部视角）；②意图用"手-物体接近度 + 运动朝向"的短时预测，不必做完整心智理论；③**默认零开销**：未检测到人时不进入任何分支。
- **所需资源**：检测器单卡数小时；真机采集少量"人干扰"片段做验证；无需新增接口。
- **落地步骤**：
  1. 人手/人体检测 + 工作区占用场；
  2. 冲突判定：人手到目标物体的距离 + 手的运动方向与目标夹角；
  3. 让行动作库：减速、后退到安全位、保持夹持；
  4. 恢复：重新分割目标、重估 `g_t`（抓握是否还在）、从任务图最近已验证子目标继续；
  5. 真机 A/B：仅人为干扰 split，比较"让行/恢复"与"继续执行"。
- **风险**：①误检导致无谓让行 ⇒ 需连续 N 帧确认 + 安全距离滞回；②人手遮挡导致目标丢失 ⇒ 用头部相机 + 记忆中的目标位姿；③"人不讲理"（故意反复干扰）⇒ 设最大让行时间，超时后回到安全保守策略而非无限等待。

### IP-11 · Recovery Mining 纠错片段挖掘（P1）

- **动机**：遥操作数据里包含人类操作者的纠错：反向、重抓、停顿后重新对准。这些片段正是"最后一步失败—恢复"的稀缺监督，但在"只学成功轨迹"的范式里被当作噪声丢弃。
- **与现有方案的差异**：常见做法是行为克隆成功轨迹；我们把**人类纠错**当作偏好/恢复信号，训练一个**恢复头**（conditioned on verifier 的失败解释）。
- **技术可行性**：中。先用规则检测候选片段（速度反向、夹爪开合反复、停顿 >T 后继续、物体相对位移异常），再用 VLM 复核；恢复头用物体无关特征（腕部几何 + 相对位姿）避免过拟合。
- **所需资源**：数据 = 官方遥操作；算力 = 小；接口 = 无。
- **落地步骤**：
  1. 写 recovery segment 检测器，统计 prevalence（预注册 <3% 即降级）；
  2. 人工抽检 5% 片段，确认标签；
  3. 训练恢复头：输入 = 失败类型 + 当前观测，输出 = 短程恢复动作块；
  4. 与 IP-02 的"重抓"合并：恢复头负责"怎么退/怎么再对准"，抓握确认负责"是否抓住"；
  5. 跨物体留出验证迁移性。
- **风险**：①片段太稀少 ⇒ 收益不显著；②恢复片段与任务强绑定 ⇒ 用物体无关特征 + 留出物体验证；③把"正常换手/换抓"误标为纠错 ⇒ 多信号投票 + 人工抽检。

### IP-12 · TLC verifier-in-the-loop 控制器（P0）

- **动机**：把 `V` 变成控制信号，而不是诊断报告。这是本轮最直接对准"终态成功"的机制。
- **与现有方案的差异**：现有策略是开环 chunk 执行；我们让任务级控制器在**安全动作集**内决策，且所有决策都受非对称门控约束。
- **状态机**：
  - `RUN`：正常执行；
  - `VERIFY`：低频/相位切换时调用 `V`；
  - `HOLD`：`V` 低置信或人在冲突区 ⇒ 停/慢/重观察；
  - `RETRY`：`V` 判定"未完成且可恢复"且重试次数 < `N_retry`；
  - `REPLAN`：任务图状态被人类改动或子目标顺序失效 ⇒ 重建子目标；
  - `STOP`：`V` 高置信完成 ⇒ 停止并保持终态（不继续动作）。
- **安全约束**：`STOP`/`RETRY`/`REPLAN` 不得直接改写高频动作均值，只能通过"暂停—重观察—重新调用策略"实现；`HOLD` 的减速有上限，避免抖动。
- **落地步骤**：①实现状态机与滞回；②用离线 rollout 标定 `τ_done`、`τ_retry`、`N_retry`；③做 stop-on-success 的收益/风险分析（L8）；④真机 A/B：完成后自毁率、超时率、成功率。
- **风险**：假完成导致早停（最大风险）；频繁 verify 增加延迟；retry 可能把已接近成功的状态破坏 ⇒ 只允许"从安全位重观察"的 retry，不允许盲目重置。

### IP-13 · Semantic Router 常识嵌入路由（P1）

- **动机**：上一轮用语言嵌入做 `z_task` 路由，兑现了 oracle 上界的一部分。常识任务图提供更强的**任务相似度**：共享子目标/前置条件的任务，其性能向量可能更相关。
- **与现有方案的差异**：把"任务相似度"从文本相似度升级为**图相似度**（子目标重叠、前置条件类型、操作原语集合），用于专家路由与迁移。
- **技术可行性**：中。任务图已由 IP-09 给出；可立即用 teaser 榜的 8×32 性能矩阵做**零成本验证**：计算图相似度与性能向量相似度的秩相关（预注册 Spearman ≥0.3）。
- **落地步骤**：①图嵌入；②与性能相似度做相关分析（E623）；③若成立，替换/融合语言路由；④路由消融。
- **风险**：图相似度不预测性能 ⇒ 退回语言路由；任务图模板主观 ⇒ 用多版本模板做稳健性检查。

## 3. 符号与定义（U13–U20）

| 符号 | 含义 |
|---|---|
| `G` | 常识任务图 `(V_g, ≺, Pre, Eff, C)` |
| `V` | 常识校验器：`(o, ℓ, G) → (p_done, p_sub, violation)` |
| `h_t` | 人类状态（在场、手位/速度、目标物体、预测意图、冲突标志） |
| `d_t` | 协调决策 ∈ {continue, yield, resume, handover-ready} |
| `R` | 恢复算子：安全位重观察 + 从最近已验证子目标继续 |
| `TLC` | 任务级控制器状态机 |
| `ρ_post` | 完成后自毁率 `post_success_regression` |
| `s_rec` | recovery segment 占比 |

**定义 U13（常识任务图）** `G = (V_g, ≺, Pre, Eff, C)`：`V_g` 为子目标；`≺` 为偏序；`Pre/Eff` 为前置条件与效果；`C` 为可观测完成判据（物体在容器内、插入到位、盖子打开等）。
**定义 U14（常识校验器）** `V(o, ℓ, G) = (p_done, {p_sub(g)}_{g∈V_g}, violation)`，其中 `p_done = P(∧_{g} completed_g | o, ℓ, G)`，`violation` 为被违反的前置条件集合。
**定义 U15（非对称完成门控）** 仅当 `p_done ≥ τ_done` 且 `violation = ∅` 时才允许 `STOP`；`τ_done` 由 L8 的收益条件确定，默认取使假完成率 ≤2% 的分位数。
**定义 U16（人类状态）** `h_t = (present, p_hand, v_hand, \hat{o}_{human}, \hat{g}_{human}, conflict)`；`\hat{g}_{human}` 为预测的人类目标物体，`conflict = 1` 当 `\hat{g}_{human}` 与机器人当前目标相同或距离小于安全半径。
**定义 U17（协调决策）** `d_t = argmax_d U(d | h_t, G, s_t)`，`U` 对碰撞/任务回退施加高惩罚，对无谓等待施加低惩罚（保守偏置）。
**定义 U18（恢复片段）** 遥操作中满足"速度反向 ∨ 连续重抓 ∨ 停顿 >T 后继续 ∨ 物体相对位移异常"的时间段，标记为 `recovery segment`。
**定义 U19（TLC 状态机）** `TLC: (s_t, V_t, h_t) → {RUN, VERIFY, HOLD, RETRY, REPLAN, STOP}`，带滞回与最大重试 `N_retry≤3`。
**定义 U20（语义路由）** `z_task = argmax_k cos(ψ(G_ℓ), ψ(G_k))`，`ψ` 为任务图嵌入；相似度低于阈值时退通用 token。

```python
# ===== UniBot-CARE 策略服务（单 checkpoint、单 API；在 UniBot-SAGE 上增量）=====
class UniBotCAREPolicy:
    def __init__(self, ckpt, ...):
        self.model = load_single_checkpoint(ckpt)   # 主干 + 专家 + (新) verifier 头
        self.gv = GraspVerifier()                    # IP-02（沿用）
        self.ctm = CommonsenseTaskModel()            # IP-09: G 模板 + 实例化
        self.verifier = VerifierHead(self.model)     # IP-09: 共享主干头
        self.tlc = TaskLevelController()             # IP-12
        self.halo = HALO()                           # IP-10
        self.recovery = RecoveryHead()               # IP-11（若启用）
        self.sessions = {}                           # 每端口隔离

    def get_action(self, obs, port=None):
        s = self.sessions[port]
        h = self.halo.update(obs)                    # IP-10: 人类状态（默认零开销）
        if h.present and h.conflict:
            d = self.halo.decide(h, s)               # yield / resume / handover-ready
            if d == "yield":
                return self.pack(self.halo.safe_retreat(obs), obs)  # 安全动作
            if d == "resume":
                s.task_state = self.ctm.relocalize(obs)             # 重建任务图状态

        # ---- IP-09/IP-12：低频 verifier + 安全决策 ----
        if s.should_verify(obs):                     # 每 K 步或相位切换
            v = self.verifier(obs, s.lang, s.G)      # (p_done, p_sub, violation)
            d = self.tlc.decide(v, h, s)             # RUN/VERIFY/HOLD/RETRY/REPLAN/STOP
        else:
            d = s.tlc_state

        if d == "STOP":                              # 高置信完成：保持终态，不再动
            return self.pack(self.tlc.hold_pose(obs), obs)
        if d == "HOLD":
            return self.pack(self.tlc.slow_or_hold(obs), obs)
        if d == "RETRY":
            return self.pack(self.recovery.act(v.violation, obs), obs)  # 安全位重观察+恢复
        if d == "REPLAN":
            s.G = self.ctm.replan(obs, s.G, v.violation)

        # ---- 正常执行：沿用上一轮动作生成 ----
        a = self.model.act(obs, s.z_task, s.z_phase, s.c, s.T_a)
        a = self.st.stitch(a, s.last_action)
        return self.pack(a, obs)
```

```python
# ===== IP-09：常识校验器（共享主干 + 几何证据）=====
class VerifierHead:
    def __call__(self, obs, lang, G):
        # 语义证据：共享 VLM 特征（不是第二个模型）
        f = self.backbone.encode(obs["images"], lang)
        p_sub = self.subgoal_head(f)                 # 每个子目标一个 logit
        viol  = self.violation_head(f)               # 多标签：未抓住/未对齐/容器未开/...
        # 几何证据：低成本、可解释
        geo = {
            "grasp":   grasp_geometry(obs),          # 夹爪闭合 + 物体随动
            "contain": bbox_containment(obs, G),     # 物体在容器内
            "insert":  insertion_depth(obs, G),      # 插入深度/对齐误差
            "support": support_relation(obs, G),     # 支撑/稳定
        }
        p_done = self.fuse(p_sub, geo)               # 校准后的融合
        return VerifierOutput(p_done, p_sub, viol, geo)

    def fuse(self, p_sub, geo):
        # 保守融合：任一硬前置不满足 ⇒ p_done 上限被压低（非对称）
        cap = 1.0
        if not geo["grasp"] and self.task_needs_grasp: cap = min(cap, 0.2)
        if not geo["contain"] and self.task_is_place:  cap = min(cap, 0.2)
        return min(self.calibrated_product(p_sub), cap)
```

```python
# ===== IP-12：TLC 状态机 =====
class TaskLevelController:
    def decide(self, v, h, s):
        if v.p_done >= self.tau_done and not v.violation:
            return "STOP"                    # L8: 高精度才停
        if h.present and h.conflict:
            return "HOLD"                    # 人优先
        if v.p_done < self.tau_fail and s.n_retry < self.N_retry:
            return "RETRY"                   # 未完成且可救
        if self.ctm.needs_replan(v.violation):
            return "REPLAN"
        return "RUN"
```

## 5. 推导（引理 L8–L12）

**引理 L8（stop-on-success 的收益条件）** 设 `V` 判"完成"的事件为 `C`，真完成为 `D`。停在 `C`：若 `D` 且继续会以概率 `d` 自毁，则收益 `d`；若 `¬D` 且继续仍可能成功（概率 `s`），则损失 `s`。故停止的期望净收益
`Δ = P(D|C)·d − P(¬D|C)·s`，
当且仅当 `P(D|C) ≥ s/(s+d)` 时 `Δ ≥ 0`。取 `s≈0.5, d≈0.1` 得阈值 `≈0.83` ⇒ **必须高精度**，这正是 P8 非对称门控的理由。∎

**引理 L9（OOD 下 PPV 塌缩）** 固定 verifier 的 TPR/FPR，正例先验 `p` 下降时
`PPV = p·TPR / (p·TPR + (1−p)·FPR)`
单调下降。未见物品/人为干扰场景恰是 `p` 最低处 ⇒ 全局阈值必然在 OOD 上产生更多假完成。故必须**分场景校准**或使用保守分位数阈值。∎

**引理 L10（意图性干扰下让行占优的条件）** 设人目标与机器人目标冲突概率为 `c`。继续执行的期望损失为 `c·L_fight`；让行的期望损失为 `(1−c)·L_delay + c·L_yield`，其中 `L_fight > L_yield`（碰撞/物体被拿走 > 延迟）。当 `c > (L_delay)/(L_fight + L_delay − L_yield)` 时让行优于继续。⇒ 在可实现"低延迟让行"时，主动让行是理性策略，而非保守退缩。∎

**引理 L11（纠错片段的可学习性）** 若恢复片段由与主策略同族的动作生成，且用物体无关特征（相对位姿、腕部几何、夹爪状态）表示，则恢复头在留出物体上的风险上界由特征分布的 Wasserstein 距离控制；当片段占比 `s_rec` 低于阈值时，经验风险方差主导，学习不可靠。⇒ 预注册 `s_rec ≥3%` 才投入。∎

**引理 L12（语义路由的可用性）** 若任务图相似度 `sim_G(i,j)` 与性能向量相似度 `sim_P(i,j)` 的秩相关 `ρ ≥ 0.3`，则按 `sim_G` 路由的期望 regret 严格小于随机路由，并可能优于纯语言嵌入路由。该命题**可在 teaser 榜 8×32 矩阵上零成本检验**（E623）。∎

|---|---|---|---|
| **假完成导致早停** | 中高 | 高（零分） | 非对称门控 + 分场景校准 + 只在高置信时 STOP；默认保留 HOLD 而非 STOP |
| **verifier 被质疑为"第二个模型"** | 中 | 中高（合规） | 共享主干 head；单 checkpoint 叙事；准备 head-only 降级 |
| **HALO 误检/误让行** | 中 | 中 | 连续 N 帧 + 滞回 + 安全距离；误让行率上限 5% |
| **人为干扰数据不足** | 中高 | 中 | 合成人手插入 + 少量真机 + 规则兜底（不依赖学习也能让行） |
| **纠错片段稀少** | 中高 | 中 | 预注册 prevalence；<3% 即降级 |
| **语义路由不成立** | 中 | 低 | 退回语言路由；零成本先验 |
| **V 调用拖慢延迟** | 中 | 中 | 低频 + 相位触发 + 蒸馏小头 + 预算门控 |
| **长尾任务没有模板** | 中 | 中 | 通用模板 + OOD token；模板只约束"检查什么" |

**剪枝预案**：
- **必保**：IP-09（判据）、IP-12（TLC）、IP-02/03/06（沿用）。
- **条件推进**：IP-10（先做"安全让行"规则版，意图预测看 E624）、IP-11（看 prevalence）、IP-13（看 E623）。
- **暂缓**：IP-05、IP-07（不直接提高完成判据可靠性）。
