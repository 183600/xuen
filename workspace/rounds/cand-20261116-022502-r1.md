# 第 10 轮（新灵感循环第 2 轮；本轮灵感：「低延迟推理」×「技术融合」）
> **基线**：第 9 轮 MetricVoiceGauge-ACMD（定义 532–539；引理 82–86；实验 E551–E570）。
> 本轮纪律：**投机验证 + 不确定性级联 + 融合运行时**。三个新机制分别治理 v9 的三笔债：**证书债**（块证书押注单一前向模型误差 ≤ β，而域偏移正是模型误差最大化的时刻）、**串行债**（5Hz 块生成 12ms 重 rollout 串行阻塞，重验证无处摊销）、**拼装债**（AC/MW/ID 三套机制各记各的账，融合只停在接口层）。任一新组件失效必须注入中立元、逐位退回 v9 ACMD（引理 90），再沿 v9 链退回 v8/v7/v6。

## 0. 直觉与动机

**灵感 1（低延迟推理 → 投机式块验证）**
直觉：LLM 服务里的 speculative decoding 之所以快，不是因为 draft 更准，而是“廉价草稿 + 一次并行验证 + 前缀接受”把 K 次串行重计算压成一次批处理。v9 的 5Hz 块生成恰是串行重计算的典型：对每个候选块做整段 rollout。核心创新：**投机块引擎（Speculative Chunk Engine, SCE）**——轻量 draft 一次生成 K 步候选，融合验证器 V 对整块做一次批式前向，逐步给出接受谓词 A_k；只执行最长接受前缀 L(t)，首次拒绝即单步修复或切最近中止点。低延迟来自“并行验证 + 前缀接受”，安全性来自“draft 只提议、verifier 逐门控”：接受前缀是 v9 可接受步的**子集**，投机只会更保守，不会更冒险。

**灵感 2（低延迟推理 → 不确定性级联与验证新鲜度）**
直觉：不是每个时刻都值得跑最重的验证；early-exit / cascade 用不确定性决定“想多深、验证多新”。核心创新：**不确定性级联控制器（Uncertainty Cascade Controller, UCC）**——把 v9 连续的 K_eff 门控升级为四级验证深度：L0 异步流水（执行上一块**已同步验证**的块，只需检查证书新鲜度）、L1 同步投机验证、L2 v9 单步证书、L3 安全停驻。升级立即、降级需迟滞；u(t) 越大、证书越陈旧，级联越深。关键不是“少算”，而是**把验证延迟从关键路径挪走，同时用新鲜度裕量显式记账**。

**灵感 3（技术融合 → 融合运行时）**
直觉：v9 的 F̂ 分别为 clearance/effort/grasp 做 rollout，6 层指标重复走骨干；AC/MW/ID 各记各的账。技术融合的要点是“共享表示、单次前向、统一记账”。核心创新：**融合运行时（Fused Runtime, FR）**——共享主干 + 多头证书（ĝ/ê/γ̂/u 一次批处理出齐）+ 跨块特征缓存（KV-cache 类比，按发散度与不确定性失效）+ draft 从 verifier 蒸馏且蒸馏容量由 ID 的贡献向量 c_m 再分配。融合不是把模块绑死，而是在契约表中共享预算与表示；任一融合组件失效仍走 v9 的独立 rollout 路径。

## 1. 研究问题（轮次升级版）

- **Q1（投机接受可靠性）**：接受谓词 A_k 需要什么条件，才能在 verifier 自身误差与 draft-verifier 误差相关性未知时，保证“已执行前缀不弱于 v9 逐步复核”？前缀接受是否引入新的“块内软通过、硬失败”空洞？
- **Q2（级联安全性）**：不确定性代理 u(t) 需满足什么校准条件，才能保证 L0/L1 的早退永不低于所需验证深度？新鲜度裕量与迟滞能否同时抑制抖振、又避免“升级太晚”？
- **Q3（融合退化性）**：共享主干、跨块缓存、draft 蒸馏如何做到“收益可加、失效可分离”——任一融合组件旁路时逐位退回 v9，而不是精度或安全上的隐性漂移？

## 2. 设计原则（在 P10–P12 基础上新增 P13–P15）

**P13 投机前缀接受律（Speculative Prefix Acceptance, SCE）**
决策以“草稿-验证-接受”为单位：draft 输出 ζ^d_t=(a^{1:K}, Ĉ^d_t)，verifier V 对整块做一次批式前向并逐步判定 A_k；只执行最大接受前缀 L(t)=max{l: ∧_{k≤l}A_k}。draft 永不直接赋予安全资格：A_k 中的间隙/effort/grasp/中止点条件**只由 verifier 判定**，divergence δ_k 只用于“拒绝更多步”。首次拒绝 r 时：若 L2 可用则执行 v9 单步证书动作，否则切最近中止点安全停驻。

**P14 不确定性级联与新鲜度律（Uncertainty Cascade, UCC）**
级联深度 ℓ(t)∈{L0,L1,L2,L3} 由校准不确定性 u(t)、风险标志与证书新鲜度裕量 M_fresh(t) 共同决定；L0 只允许执行“上一块已同步验证且仍新鲜”的前缀。升级（ℓ 增大）立即生效，降级需连续 h_down 个周期满足低一级条件；任何新鲜度裕量为负、risk_SLAM 越阈或 M₀ 硬检查触发，直接跳到 L2/L3。

**P15 融合可分离律（Fusible-but-Separable Runtime, FR）**
每个融合组件（共享主干、多头证书、前缀缓存、draft 蒸馏、相关性审计）都带独立 bypass 开关；bypass=True 时走 v9 保留的原始代码路径，输出逐位一致。融合收益须可分解记账（延迟、算力、接受率），不得以“整体更快”掩盖单组件失效。

## 3. 与基线的接口（如何退化）

- SCE 失效（接受率异常 / verifier 批处理超时 / draft 崩溃）⇒ 关闭投机，整块走 v9 单候选完整 rollout，等价 v9 AC；
- UCC 失效 ⇒ ℓ 固定为 L2（同步单步），等价 v9 决策深度；
- FR 失效 ⇒ 关缓存、停蒸馏、多头拆回独立 F̂ rollout，逐位走 v9 路径；
- DAud 失效 ⇒ η←0（不容忍发散，只有精确一致才接受），退化为最保守的验证子集，必要时 K=1；
- v9 的 AC/MW/ID 任一失效 ⇒ v9 中立元链（K_eff←1 / 手写网关 / 全模块 active）；
- v8 的 DA/SPR/Cal 失效 ⇒ 注入中立元（Δ_dom≡0 / risk_SLAM≡0 / sensor_weight≡1），等价 v7；
- 全部失效 ⇒ 完整退回 MetricVoiceGauge-OTL-GC-ER v7，再退回 v6。

## 4. 预期贡献

1. **投机式块验证框架**：把 speculative decoding 的 draft-verify-accept 迁移到带安全证书的实时决策，并给出“接受前缀 ⊆ v9 可接受步”的保守性条件与延迟模型；
2. **不确定性级联与验证新鲜度**：用校准的 u(t) + 新鲜度裕量把 v9 连续 K_eff 门控升级为可证明的验证深度调度，L0 异步流水把验证从关键路径移走；
3. **融合运行时**：共享主干多头证书 + 跨块缓存 + 归因加权蒸馏，给出“收益可加、失效可分离”的退化代数；
4. **实验闭环 E571–E590**：覆盖接受率-延迟 Pareto、前缀安全、相关性压力测试、级联校准、缓存时效、融合消融、逐位退化与端到端。

## 5. 本轮最大风险

**一句话**：投机验证的安全性依赖 draft 与 verifier 的误差不相关，而域偏移恰恰会同时驱动两者犯错并让它们“相互一致”；此时发散度 δ 很小、接受谓词会高置信地接受一个错误块——低延迟把安全押在“误差独立性”这个最脆弱的假设上，而 DAud 对相关性的在线估计本身也可能被同一次偏移欺骗。

## 1. 符号体系增量（定义 540–549）

| 符号 | 含义 |

| α(t)=E[L(t)]/K_eff | 接受率 |
| C_d, C_v(B), C_r | draft 单候选成本、批验证 B 个候选成本、单步修复成本 |

| M_fresh(t) | 证书新鲜度裕量（定义 546） |

| ρ_e | draft 误差与 verifier 误差的在线相关系数估计 |
| K_cache, ρ_hit | 前缀缓存槽数与命中率 |

**新增定义 540（投机块 SpeculativeChunk）** draft 策略 π_d（量化单层/小骨干）对状态 s_t 一次生成 K=K_eff(t) 步候选与 draft 证书：ζ^d_t=(a^{1:K}, Ĉ^d_t)，其中 Ĉ^d_t=(ĝ^d_min, ê^d_max, γ̂^d)。draft 成本 C_d≪C_rollout（v9 单候选完整 rollout 成本）。**draft 输出仅进入接受谓词的 δ_k 项，永不单独构成安全通过条件。**

**新增定义 541（融合验证器 FusedVerifier）** V 由共享主干 φ 与四个头组成：h_g（间隙）、h_e（effort）、h_γ（抓取可行性）、h_u（不确定性）。对一批候选块做**一次批式前向**：
```
(ĝ^{1:K}, ê^{1:K}, γ̂^{1:K}, û^{1:K}) = V(s_t, a^{1:K})
```
在信任域 U_t（v9 定义 539）内，V 的间隙头满足 v9 同款一致误差界：∀k, g_k ≥ ĝ_k − β_V（β_V 由 E578 与 v9 E554 联合标定）。批量大小 B、槽位并行；V 冻结，不参与在线梯度。

**新增定义 542（接受谓词与接受前缀 AcceptancePrefix）** 第 k 步接受当且仅当五个条件同时成立：
```
A_k = [δ_k ≤ η]                                    # draft-verifier 一致（仅收紧）
    ∧ [ĝ_k − β_V ≥ d_safe]                         # 间隙证书（verifier 判定）
    ∧ [ê_k + β_V ≤ τ_eff]                          # effort 证书
    ∧ [γ̂_k = valid]                                # 抓取可行
    ∧ [∃p∈P_t, p ≥ k]                              # 存在不早于 k 的中止点（v9 定义 534）
L(t) = max{ l ∈ [0,K] : ∀k≤l, A_k }                # 接受前缀
```
若 L(t)≥1，执行 a^{1:L}；若 0<L(t)<K，首次拒绝步 r=L+1 触发修复：L2 可用则执行 v9 单步证书动作，否则切 ≤r 的最近中止点安全停驻；L(t)=0 时整块拒绝，走 v9 单步/停驻。

**新增定义 543（延迟模型 LatencyModel）** 设 draft 候选数 n_d、送验证的 top-B 候选、接受率 α，则单次 5Hz 块生成期望延迟：
```
E[T_block] = n_d·C_d + C_v(B) + (1−α)·E[C_r | reject]
```
其中 C_v(B)=c_0+c_1·B（批处理/槽位并行，近似亚线性）。v9 为 T_9 = n·C_rollout（n=64 个候选各做整段重 rollout）。50Hz 单周期摊销：E[T_block]/K_eff + C_guard + C_inherited。α 越高、B 越小（并行越好），延迟越低；η 控制 α 与安全的权衡（引理 92）。

**新增定义 544（逐步发散度 StepDivergence）** 归一化证书差：
```
δ_k = max( |ĝ_k − ĝ^d_k| / Δ_g , |ê_k − ê^d_k| / Δ_e , 1[γ̂_k ≠ γ̂^d_k] )
```
Δ_g、Δ_e 为对应指标量程。δ_k 只度量“两个模型是否说同样的话”，**不度量“它们是否都错”**——后者由 IP-360 专门审计（定义 549）。

**新增定义 545（校准不确定性代理 CalibratedUncertainty）**
```
u(t) = clip( w_1·Var_ens(V)(s_t) + w_2·(Δ_dom(t)/τ_dom)
           + w_3·|residual_cal(t)|/σ_cal + w_4·(1 − δ̄(t)/η), 0, 1 )
```
Var_ens 为 V 的轻量集成/ dropout 头方差，residual_cal 为最近一次在线标定残差。u 必须在留出集上做**上界校准**：存在 θ_0 使 P(真实单步误差 > β_V | u ≤ θ_0) ≤ ε（E575 用 conformal/分位数回归验证）。u 只是代理，校准失效是本轮最大风险的结构性来源。

**新增定义 546（验证级联、新鲜度与迟滞 VerificationCascade）** 级联深度：
```
ℓ(t)=L0  若 u<θ_1 ∧ ¬risk_flag ∧ M_fresh(t)≥0 ∧ δ̄≤η
     =L1  若 u<θ_2 ∧ ¬risk_flag ∧ M_fresh(t)≥0
     =L2  若 u<θ_2 但 M_fresh(t)<0，或 risk_SLAM≥τ_SLAM
     =L3  若 u≥θ_2 或 M₀ 硬检查触发或停车不变式已破坏
```
- **L0 异步流水**：执行上一块**已同步验证**的前缀；本块验证在后台进行。新鲜度裕量：
  ```
  M_fresh(t) = τ_fresh − (t − t_verify) − λ_s·‖s_t − ŝ_{t_verify}‖ − λ_u·u(t)
  ```
  其中 ‖s_t−ŝ‖ 为实测状态相对验证时预测状态的漂移。M_fresh<0 ⇒ 证书可能已过期，禁 L0。
- **L1 同步投机**：本块验证完成后再执行（SCE 全流程）。
- **L2 v9 单步**：K_eff=1，逐周期证书。
- **L3 安全停驻**：切最近中止点或指数减速停车。
- 升级（ℓ 数值增大）立即生效；降级需连续 h_down 个周期满足目标级条件，且降幅每次至多一级。

**新增定义 547（前缀特征缓存 PrefixFeatureCache）** 以 key=(round(s_t,ε_state), hash(a^{1:k})) 缓存验证器主干特征 φ(s_t,a^{1:k})；命中则跳过主干重算（只跑轻量头）。失效条件：δ_k>η、u 突增（Δu>θ_2−θ_1）、状态漂移 >ε_state、或 t−t_cache>τ_fresh。缓存只存**特征**，不存安全结论；安全结论每次由头重新计算。命中率 ρ_hit 计入复杂度与实验 E579。

**新增定义 548（归因加权蒸馏 DistillByAttribution）** draft 由 verifier 蒸馏，各头容量/损失权重由 v9 的贡献向量 c_m 再分配：
```
L_distill = Σ_m c_m·E[ ‖h_m^draft(s,a) − sg(h_m^V(s,a))‖² ] + λ_kl·KL(π_d ‖ π_V)
```
c_m 沿用 v9 定义 537 的滑窗消融 EMA；安全关键头（h_g、h_γ）设 c_m≡1（不可降权）。蒸馏只更新 draft，不更新冻结的 verifier；ID 失效 ⇒ c_m 冻结，蒸馏退化为均匀权重。

**新增定义 549（发散-误差相关性审计 DivergenceAudit）** IP-360 在滑动窗口 W 内估计
```
ρ_e = corr( δ_k , |ĝ_k − g_k^true| )      # 用可获得的真值/高保真仿真回放
```
当 ρ_e>η_corr 或 δ 与误差出现**反相关**（δ 小但误差大）时，判定“draft 与 verifier 相关失效”，执行：η←η/2、冻结 L0 一个 τ_fresh 窗、强制 ℓ≥L1；若持续 3 窗超阈，强制 ℓ≡L2 并告警。审计器自身失效 ⇒ 按 Level-4 处理（η←0，保守）。

# IP-357 SpeculativeChunkEngine：投机块引擎
class SpeculativeChunkEngine:
    def __init__(self, draft, verifier, K_max=10, eta=0.05, beta_V=0.02,
                 d_safe=0.15, batch_B=8, n_draft=64):
        self.d, self.V = draft, verifier
        self.K_max, self.eta, self.beta_V = K_max, eta, beta_V
        self.d_safe, self.B, self.n_draft = d_safe, batch_B, n_draft

    def propose(self, state, K):
        cands = self.d.sample(state, K, n=self.n_draft)      # 廉价 draft 提议
        return self._top_b(cands, self.B)                     # draft 自评分取 top-B

    def verify_batch(self, state, cands):
        # 一次批式前向：共享主干 + 四头（定义 541）
        return self.V.batch_forward(state, cands)             # g,e,gamma,u for 1..K

    def accept_prefix(self, state, cand, out):
        L, abort_ok = 0, state.abort_points(cand.actions)     # P_t（v9 定义 534）
        for k in range(1, len(cand.actions) + 1):
            delta = self._divergence(out, cand.draft_cert, k) # 定义 544
            ok = (delta <= self.eta
                  and out.g[k] - self.beta_V >= self.d_safe
                  and out.e[k] + self.beta_V <= state.tau_eff
                  and out.gamma[k] == 'valid'
                  and any(p >= k for p in abort_ok))
            if not ok:
                break
            L = k
        return L

    def generate(self, state, K):
        best = None
        for cand in self.propose(state, K):
            out = self.verify_batch(state, [cand])[0]         # 槽位并行
            L = self.accept_prefix(state, cand, out)
            if L > 0:
                score = self._score(cand, out, L)
                if best is None or score > best.score:
                    best = Accepted(cand, L, out, score)
        if best is None or best.L == 0:
            return self._v9_single_step(state)                # 退化：v9 单步
        return best


# IP-359 FusedRuntime：融合运行时（共享主干 + 多头 + 缓存 + 蒸馏）
class FusedRuntime:
    def __init__(self, trunk, heads, cache, draft=None):
        self.trunk, self.heads = trunk, heads
        self.cache, self.draft = cache, draft

    def batch_forward(self, state, cands, use_cache=True):
        outs = []
        for cand in cands:
            feats, hit = [], False
            for k, a in enumerate(cand.actions, 1):
                key = self.cache.key(state, cand.actions[:k])
                if use_cache and (f := self.cache.get(key)) is not None:
                    feats.append(f); hit = True
                else:
                    f = self.trunk(state, cand.actions[:k])
                    self.cache.put(key, f); feats.append(f)
            h = {name: [head(f) for f, head in zip(feats, self.heads[name])]
                 for name in ('g', 'e', 'gamma')}
            h['u'] = self.heads['u'](feats[-1], hit=hit)      # 不确定性头
            outs.append(Out(h))
        return outs

    def distill_step(self, batch, c_m):
        # 定义 548：按 ID 贡献加权，只在后台/低优先级运行
        for m in ('g', 'e', 'gamma'):
            w = 1.0 if m in ('g', 'gamma') else c_m.get(m, 1.0)
            loss = w * mse(self.draft.heads[m](batch), self.heads[m](batch).detach())
            self.draft.optimizer.zero_grad(); loss.backward(); self.draft.optimizer.step()


# IP-358 UncertaintyCascadeController：不确定性级联
class UncertaintyCascadeController:
    def __init__(self, theta=(0.25, 0.55, 0.80), h_down=5):
        self.th, self.h_down = theta, h_down
        self.level, self.lower_streak = Level.L2, 0

    def min_level(self, u, risk_flag, m_fresh):
        if u >= self.th[2] or risk_flag == 'hard': return Level.L3
        if m_fresh < 0 or risk_flag == 'slam':     return Level.L2
        if u >= self.th[1]:                        return Level.L2
        if u >= self.th[0]:                        return Level.L1
        return Level.L0

    def step(self, u, risk_flag, m_fresh):
        target = self.min_level(u, risk_flag, m_fresh)
        if target > self.level:                            # 升级立即
            self.level = target; self.lower_streak = 0
        elif target < self.level:                          # 降级迟滞
            self.lower_streak += 1
            if self.lower_streak >= self.h_down:
                self.level = Level(self.level - 1); self.lower_streak = 0
        else:
            self.lower_streak = 0
        return self.level


# IP-360 DivergenceAuditor：相关性审计（本轮风险的守门人）
class DivergenceAuditor:
    def __init__(self, eta_corr=0.6, window=50):
        self.eta_corr, self.W = eta_corr, window
        self.deltas, self.errors = deque(maxlen=window), deque(maxlen=window)

    def update(self, delta, true_error):
        self.deltas.append(delta); self.errors.append(true_error)
        if len(self.deltas) < self.W:
            return 'ok'
        rho = corr(self.deltas, self.errors)
        if rho > self.eta_corr or rho < 0.0:               # 正相关过强或反相关
            return 'correlated_failure'
        return 'ok'

## 4. 推导

**引理 87（前缀接受的保守性）** 设 verifier V 在信任域 U_t 内满足与 v9 F̂ 同款的单步误差界 g_k ≥ ĝ_k − β_V，且接受谓词 A_k 的间隙/effort/grasp/中止点条件全部由 V 的证书判定。则对被执行的任意接受步 k≤L(t)，真实间隙 g_k ≥ d_safe；即“接受前缀执行”是 v9 逐步证书可接受步集合的**子集**，不引入新的块内空洞。证明：A_k 含 ĝ_k−β_V ≥ d_safe，由误差界得 g_k ≥ ĝ_k−β_V ≥ d_safe；δ_k≤η 只是一项额外的拒绝条件，去掉它只会扩大集合，故 A_k ⇒ v9 第 k 步接受。对 k≤L 归纳，前缀内每步均满足；中止点条件继承定义 534。∎

**引理 88（投机延迟收益界）** 在定义 543 的模型下：
```
E[T_SCF] = n_d·C_d + C_v(B) + (1−α)·E[C_r]
```
若 C_d ≤ C_rollout/(n·K)（draft 远廉于完整 rollout）、C_v(B) ≤ ρ·n·C_rollout（批验证并行摊销，ρ<1）、且 α≥α_min，则 E[T_SCF] ≤ T_9 − [(1−ρ)n·C_rollout − n_d C_d − (1−α)E[C_r]]。实例：n=64, K=10, T_9=12ms；n_d C_d≈3.2ms，C_v(8)≈2.5ms，修复项≤0.8ms ⇒ E[T_SCF]≈6.5ms，块生成降幅≈46%；50Hz 摊销后典型 ≤0.65ms/cycle。∎

**引理 89（级联安全条件与无抖振）** 若 u 满足定义 545 的上界校准（P(err>β_V | u≤θ_0)≤ε），且 L0 执行前检查 M_fresh(t)≥0，则 L0 执行的旧验证前缀仍以概率 ≥1−ε 满足单步证书；M_fresh<0 或风险标志强制 L2，故不存在“旧证书过期仍执行”的路径。迟滞方面：升级立即、降级需 h_down 个连续周期且每次降一级，故任意窗口内降级次数 ≤ ⌈W/h_down⌉，迁移率有界，无 Zeno。∎（注：结论条件于 u 的校准，见本轮风险。）

**引理 90（融合退化等价）** 对每个新组件取 bypass：
- SCE.bypass=True ⇒ 调用 v9 `ActionChunkCertifier.generate_chunk`（全候选完整 rollout）⇒ 逐位等价 v9 AC；
- UCC.bypass=True ⇒ ℓ 恒为 L2（同步单步）⇒ 逐位等价 v9 决策深度；
- FR.bypass=True ⇒ V 替换为 v9 F̂ 独立 rollout，禁用 cache 与 distill ⇒ 逐位等价 v9；
- DAud.bypass=True ⇒ η=0（只接受精确一致，否则拒绝）⇒ 接受前缀是 v9 可接受步的子集（引理 87），必要时 K=1。
各旁路可组合；组合后输出 = v9 ACMD，再沿 v9 引理 83→80–81 退到 v8/v7。∎

**引理 91（蒸馏校准界与接受率）** 设 h_m^V 为 L-Lipschitz，ID 归因 EMA 误差 ≤ε_c，draft 基线蒸馏误差 ≤ε_d0，则每头 draft 误差 ≤ L·ε_c+ε_d0。由 δ 的归一化定义与 Markov 不等式，
```
α(η) = P(δ≤η) ≥ 1 − (L·ε_c + ε_d0)/η
```
故归因越稳（ε_c↓），同 η 下接受率越高，或可收紧 η 以换取同接受率下的更高安全裕量。∎

**引理 92（接受率-安全的单调权衡）** 对固定 draft/verifier，定义危险接受数 S(η)=Σ_k 1[δ_k≤η ∧ g_k<d_safe]。由于 δ_k≥0，S(η) 关于 η 单调不减，α(η) 关于 η 单调不减，而 E[T] 关于 α 单调不增（引理 88）。因此存在 Pareto 前沿；给定每小时危险接受预算 λ_target，取 η* = min{η : E[S(η)]/hour ≤ λ_target} 即得最小延迟的安全可行点（E574 标定）。∎

## 8. 本轮最大风险

**一句话**：投机验证的安全性依赖 draft 与 verifier 的误差不相关，而域偏移恰恰会同时驱动两者犯错并让它们“相互一致”；此时 δ 很小、接受谓词会高置信地接受一个错误块——低延迟把安全押在“误差独立性”这个最脆弱的假设上，而 DAud 对相关性的在线估计本身也可能被同一次偏移欺骗。
