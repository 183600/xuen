# 第 2 轮（新循环）· CHRONO-BT：把评分表编译成时空行为树

> 检索/复核日期：2026-10-24（UTC）。赛事身份不变：宇树科技 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「时空推理」「行为克隆」「行为树」。先纠正一条会改变预算的关键规则，再把三个词各钉到一个失败模式，最后合成主判断：**榜首不到 30% 的主要瓶颈不是“不会看”，而是“做不完、做不稳、被扰动后回不来”；把官方 `score_steps` 编译成运行时行为树，用多时间尺度历史学习每一步的守卫，用相位条件化的单一 VLA 当树叶，把“近失”转成“完整成功”，比继续堆大模型或抠步骤分更划算。** 这是新循环第 2 轮，承接 `research.md` 第 7 轮 PILOT 基线，不推倒重来。

## 0. 先纠正一条规则：排名是成功率优先，步骤分只是平局裁判

第 7 轮把排名写成“成功率与步骤分综合排序”，这不准确。官方参赛手册写得很清楚：

> “实时榜单按 32 个任务的 **总平均成功率** 进行排序，成功率相同时按 **总平均步骤分** 排序，若仍相同，则提交日期较早的模型排序靠前。”[S1][S2]

同一份手册还确认了三条硬约束：

- 每个任务在 **10 次独立运行** 中评测，5 种泛化类型各出现 **2 次**；单次真机执行上限 **180 秒**，超时记失败。[S1][S2]
- 必须是 **单一模型** 完成全部 32 个任务，不得按任务混用多个模型；模型类型不限（World Model、VLA 均可）。[S1][S2]
- 另有不计分的单任务调试通道，但结果不进排行榜。[S1][S2]

这个纠正改变三件事：

1. **不要用成功率换步骤分。** 一个“拿到 30 分但终局失败”的放置，不如一个“慢一点但完整成功”的重试。步骤分只在成功率打平时才兑现，不能作为主目标。
2. **恢复/重试的价值被低估了。** 排行榜按成功率排序，意味着“把接近成功的 episode 救回来”是直接收益；而“多做半步拿部分分”不是。
3. **统计噪声比第 7 轮估计的更大。** 32×10=320 次计分 trial；若真实成功率 p≈0.3，二项标准误约 `sqrt(0.3×0.7/320)≈2.6pp`，95% 区间约 ±5pp。每个泛化轴只有 64 次 trial，SE 约 5.7pp。**不要用 2 次/轴/任务的样本去断言“某轴被解决”**；应看 32 任务配对差异和 bootstrap 区间。

第 7 轮的 3200 分、终局 1275 分（39.8%）、放置类约 1910 分（59.7%）仍然有价值，但它们的角色从“目标函数”降为“诊断工具”：告诉我们成功通常死在哪一步、哪些步骤最值得做恢复。**终局放置仍然是 32/32 任务的成功闸门，但理由从“它占 39.8% 分数”变成“它是 success 的必要条件”。**

## 1. 三个灵感词，各钉到一个可检验的失败模式

### 1.1 时空推理 → 状态别名、进度回归、对象永久性

长程操作里，视觉上几乎相同的帧可能对应完全不同的阶段：碗已经叠上去了 vs 还没叠；拉链已经拉上 vs 被拉开；插头已经插入 vs 只顶在门口。标准 BC 策略在推理时是马尔可夫的，看到相似观测就倾向输出相似动作，这就是 **state aliasing**。[S19]

三条证据把“时空推理”从口号变成具体机制：

- **ST-π** 用 4D 观测和 chunk 级动作提示（子任务、空间 grounding、时间 grounding）显式表示阶段边界，说明“把时空结构显式化”比让模型隐式猜更稳。[S13]
- **ST-VLA** 用统一的 3D-4D 表示和空间掩码连接高层推理与低层控制，说明时序一致性可以作为一个可训练接口。[S14]
- **Temporal Forcing** 进一步指出：只把历史拼进观测，并不保证策略真的用了历史；需要用 4D 表征目标直接监督“状态及其转移”的 latent。它在 LIBERO-Long 和 RoboTwin 2.0 上的增益，支持“历史要用对，而不是只用上”。[S15]

对 UniBot 的直接含义：人为干扰轴的大量备注是“把物体平移”或“某步完成后撤销”（T27 叠了第二个之后拿下第二个；T19 拉上拉链之后拉开；T14 拧开盖子之后拧回来）。[S4] 这些不是新的语义类别，而是 **同一观测分布下的状态回归**。如果策略没有“当前在第几步、上一步是否还成立、目标物是否还在”的记忆，它就会把“被撤销”误当成“已完成”，然后继续往下做，最后整题失败。

### 1.2 行为克隆 → 复合误差、非马尔可夫演示、开环反应性

行为克隆在长程任务上的核心问题不是“拟合能力不够”，而是误差沿时间复合。2026 年关于 action chunking 的两篇工作把机制讲清楚了：

- **Action chunking** 的收益主要来自更强的非马尔可夫表达力、降低复合误差，以及“隐式集成”（同一观测在不同时间偏移下预测多个动作，形成多样性）。[S16]
- 但 **长开环 chunk 会降低反应性**；当策略有足够上下文时，闭环重规划可以更好，长开环主要在“短上下文策略模仿非马尔可夫演示”时才有优势。[S17]
- **BC 稳定性** 的测量进一步显示，误差放大在状态空间中很常见，且短窗口容易高估长期传播；开环/闭环的选择应该由状态决定，而不是全局固定。[S18]

对 UniBot 的直接含义：不要迷信“chunk 越长越稳”。更合理的配方是 **中等长度 chunk + 足够历史 + 在步骤边界/守卫失败时触发重规划**。行为克隆提供动作先验，行为树提供“什么时候该停止开环、什么时候该重试”的调度。另一个直接推论是数据质量：如果演示里混入失败段、停顿段、无进展段，BC 会学到“卡住”的先验；应该用评分步骤做 **分段、过滤、重加权**，而不是把 33k 整段灌进去。

### 1.3 行为树 → 结构化执行、前置/后置条件、失败恢复

行为树（BT）不是新东西，但它在 2025-2026 年的机器人系统里重新变得重要，原因是它把“执行结构”从模型里拿出来，变成可检查、可回退、可恢复的控制器：

- **VLM + reactive planner + BT** 的统一失败恢复框架，用 scene graph 和 execution history 做预执行检查与执行中恢复，在插销、分拣、抽屉放置等任务上优于单独的预检查或单独的反应式方法。[S24]
- **BT-Agent** 把 LLM 的任务决策与预定义 BT 技能结合，BT 技能负责执行条件与结构化失败反馈；局部检查可以在不等待下一次模型决策的情况下中止错误动作，4B/9B 模型上相对最强 Act/ReAct 基线约有 10/5 个点提升。[S25]
- **SeqVLA** 给 π0 加一个完成检测头，说明“子任务何时结束”本身就是一个可学习的信号；但它只有完成头，没有 BT 的 fallback/backtracking。[S20]
- **CycleVLA** 进一步做进度感知 + VLM 失败预测 + 子任务回溯 + MBR 解码，真机三个任务平均 91%；代价是测试时多了一个 VLM 预测/规划器。[S21]

对 UniBot 的直接含义：**官方 `score_steps` 已经把任务分解和成功条件公开了**，不需要测试时再让 LLM 规划。把它编译成 BT，用单一 VLA 当树叶，用学习到的守卫检查前置/后置条件，用 BT 做 retry/backtrack/recover——这是“行为树”这个词在本赛题里最直接的落点，也是与“再堆一个 VLM 规划器”的关键区别。

## 2. 主判断：不是更大的 VLA，而是把评分表变成运行时控制器

榜首不到 30%，但头部模型的语义/空间 grounding 并不弱：MolmoAct2 专门做空间与具身推理，WALL-OSS-0.5 在 20+ 形态、百万级轨迹上预训练，DreamZero 用视频扩散学物理动力学，π0.5 做异构 co-training 与高层子任务预测，GR00T N1.5 用冻结 VLM + DiT 动作专家。[S27][S28][S29][S30][S32] 他们缺的不是“看懂场景”，而是：

- 当前处在第几步、这一步是否真的完成；
- 长程执行中误差如何不复利；
- 目标被移动/步骤被撤销后如何发现并回到正确阶段；
- 终局放置/插入后如何验证“真的成了”，而不是“手松开了”。

所以本轮的主判断是：

> **把公开评分步骤编译成运行时行为树；用相位条件化的单一 VLA 做树叶；用多时间尺度历史学习每一步的完成、进度、回归、扰动守卫；把测试时算力全部花在“把近失转成完整成功”上。**

三个支撑论点：

1. **评分表是免费的、与评测同构的步骤级监督。** `score_steps` 给出每步文本、顺序、分值；`scoring_points` 给出更细的中文描述；5 条英文复述给出语言鲁棒性先验。[S4][S12] 这比“用 LLM 猜子任务”更可靠，也比“只用 episode 级语言”更接近评测。
2. **一个策略可以服务所有阶段，但需要一个外部状态机。** 相位条件化让同一 checkpoint 在不同阶段产生不同行为（FiLM/phase token），避免 state aliasing；BT 提供离散状态、前置/后置条件和 fallback，不需要为每个任务训练一个模型。[S19]
3. **成功率优先的排名，使恢复成为最高杠杆。** 320 次 trial 里，真正“完全不会”的失败可能占一部分，但更多是“做到后半段失败”。若近失约占失败的三分之一，救回其中 20% 约等于 +4-5pp 的总成功率；这比在单个泛化轴上抠 2-3pp 更稳。

**什么情况下这个判断会被推翻？** 如果离线步骤级诊断显示，失败主要集中在“抓取点/放置点根本找错”（空间 grounding），而不是“完成检测/恢复”，那就回到第 7 轮的 PGL/OPT 主线；如果 BT 恢复在调试槽里不能把近失转成成功，就砍掉 BT 恢复，只保留相位条件化。这个方案必须带着停止条件上线。

## 3. 方案轮廓：CHRONO-BT

```text
官方 score_steps + scoring_points + 5 条复述
              │
              ▼
      Rubric Compiler（离线，确定性）
              │  每任务一棵 BT：
              │  Seq( Retry( Guard(post) → Leaf(phase) ), Fallback(...) )
              ▼
   ┌────────────────────── 推理期（单一 checkpoint）──────────────────────┐
   │ 4 路 RGB + proprio + 语言 + 历史（短/长/4D 对象记忆）                  │
   │        │                                                             │
   │        ├─► STG 时空守卫：完成 c、进度 p、回归 r、扰动 d、目标存在 o    │
   │        │                                                             │
   │        └─► π_θ(a_chunk | 历史, 语言, 相位 z_s, 目标上下文 g_s)        │
   │                          │                                           │
   │                          ▼                                           │
   │  BT Runtime：前置检查 → 执行 → 后置检查 → 前进/重试/回溯/恢复          │
   │              180s 时间守卫；关键步可选 Tree-of-Chunks                  │
   └──────────────────────────────────────────────────────────────────────┘
              │
              ▼
   离线：RF-BC 分段/过滤/重加权 + RDE 官方备注恢复数据 + PGL/OPT 放置子技能
```

组件与是否进推理：

| 组件 | 作用 | 进推理？ |
|---|---|---|
| RC（Rubric Compiler） | 把 `score_steps` 编译成 BT；确定性代码 | 是（代码，非模型） |
| PCP（Phase-Conditioned Policy） | 单一 VLA；相位 token/FiLM；输出 action chunk | 是（唯一学习模型） |
| STG（Spatiotemporal Guard） | 完成/进度/回归/扰动/目标存在多头 | 是（同一 checkpoint 的辅助头） |
| BTR（BT Runtime） | 前置/后置检查、retry、backtrack、recover、时间守卫 | 是（确定性代码） |
| RF-BC | 评分步骤分段、失败段过滤、相位重加权 | 否（离线数据） |
| RDE | 用官方 human 备注构造 undo→recover 数据 | 否（离线数据） |
| PGL/OPT/SVL | 放置目标阶梯、少样本位姿迁移、落点校验 | 是（作为 BT 叶子/fallback） |
| ToC | 关键步采样 K 个 chunk，守卫打分选优 | 可选（测试时算力） |
| L2L/DebugLoop | 实验室数据、平台调试槽 | 否（流程） |

**一句话**：评分表提供结构，相位条件化提供共享技能，时空守卫提供状态，行为树提供恢复；四个东西都不需要第二个大模型。

## 4. 与第 7 轮的关系：升级，不是换题

| 第 7 轮 | 本轮 | 关系 |
|---|---|---|
| SSG 评分步骤图 | **CHRONO-BT** | 从线性状态机升级为带 retry/fallback/backtrack 的行为树 |
| SVL 落点 settle-verify | BT 的后置条件 + fallback | 折成终局步的验证叶子 |
| NRB 官方备注恢复库 | **RDE 恢复数据引擎** | 从“训练数据”升级为“BT 触发 + 相位 recover 数据” |
| PGL/OPT 放置子技能 | 保留 | 作为 BT 的放置叶子/候选动作 |
| ICR 上下文检索 | 降为可选目标上下文 | 不再作为主回路，避免延迟 |
| “按步骤权重分配重试” | **成功率优先重试** | 排名规则纠正后的直接结果 |
| TCLB / FLEET | 继续降级 | 工程检查单/离线比较，不做研究主轴 |

**新增创新点**：

- **I1 CHRONO-BT**：评分表编译的运行时行为树（主押注）。
- **I2 PCP**：相位条件化的单一 VLA（FiLM + phase token），解决 state aliasing。
- **I3 STG**：多时间尺度时空守卫（完成/进度/回归/扰动/目标存在）。
- **I4 RF-BC**：评分表过滤的行为克隆数据引擎（分段、去失败段、相位重加权）。
- **I5 RDE**：官方 human 备注驱动的 undo→recover 数据与 recover 相位。
- **I6 ToC**：关键步 Tree-of-Chunks 测试时算力（可选）。

## 5. 可证伪的预言

| # | 预言 | 度量 | 停止条件 |
|---|---|---|---|
| H1 | 相位条件化降低 state aliasing | 离线完成检测 F1 +10pp；闭环成功率 +3pp | 离线 F1 不升 → 回退 token-only |
| H2 | BT + STG 把近失转成成功 | 近失 episode 恢复率 ≥20%；若近失占失败 1/3，总成功率 +4-5pp | 恢复率 <10% → 砍 BT 恢复 |
| H3 | 成功率优先重试优于步骤分优先 | 成功率 +2-4pp，步骤分不显著下降 | 成功率不升 → 回退贪心完成 |
| H4 | 评分表 BT 优于扁平/通用分层 | 同数据同算力下 +5pp | 无差异 → BT 只保留诊断 |

统计上，320 次 trial 的 95% 区间约 ±5pp；目标定在 **+5pp**，用 32 任务配对 bootstrap，不用单轴 2 次样本讲故事。

## 6. 风险与合规（先立后破）

- **单模型边界**：唯一学习模型是一个 checkpoint（VLA + 相位嵌入 + STG 辅助头）；BT/RC 是确定性代码，不是模型；RDE/RF-BC 是离线数据。测试时不调用第二个 VLM/LLM。模型卡写清楚。
- **任务特定代码**：BT 由公开评分表编译，不是 32 个任务模型；若主办方对“任务特定代码”有异议，退化为一个通用 BT 模板 + 评分表作为数据，仍是单模型。
- **外部数据**：已读手册未明确允许/禁止；默认只用官方 33k + 公开预训练权重，实验室数据默认 OFF，邮件确认后再开。[S1][S2]
- **延迟**：6B 模型单次 forward 目标 p99 <150ms；chunk=16（约 1s 动作）吸收延迟；BT tick <5ms；STG <10ms；ToC 只在终局/插入等关键步开 K=2-4。
- **误判**：STG 阈值用 conformal/温度校准 + 滞回；高置信才前进，低置信触发重试而不是硬切；保留确定性谓词兜底。
- **统计**：320 trial，别用 2 次/轴/任务断言；正式跑前后都做配对 bootstrap。
- **调试槽**：不计分单任务调试是发布门，不是调参器；每个大版本最多 1 槽。[S8]
- **安全**：关节限位、碰撞检查、180s 总时长守卫；恢复动作不能把物体扫到桌外。

## 7. 一句话押注

**把公开评分步骤编译成运行时行为树，用相位条件化的单一 VLA 做树叶、用多时间尺度 4D 历史学习每一步的完成/回归/扰动守卫，并把重试预算全部押在“把近失转成完整成功”上——这是在不增大模型的前提下，同时打穿成功率闸门和人为干扰轴的最短路径。**

# 第 2 轮（新循环）产物区 · CHRONO-BT 技术报告

> 目标赛事：宇树科技 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署、官方远程真机 API 评测。检索/复核日期：**2026-10-24（UTC）**。本报告承接第 7 轮 PILOT-GPR，但把主线从“终局放置优先”升级为“**评分表编译的时空行为树 + 相位条件行为克隆 + 成功率先行恢复**”。本轮最重要的新事实不是又一个模型，而是官方手册明确了排名规则：**总平均成功率优先，步骤分只在平局时使用**。[S1][S2]

## 0. 产物摘要

### 0.1 一句话

**把公开的 `score_steps` 编译成运行时行为树，用相位条件化的单一 VLA 做树叶，用多时间尺度 4D 历史学习每一步的完成/进度/回归/扰动守卫，并把测试时算力全部押在“把近失转成完整成功”上。**

### 0.2 组件与是否进推理

| 组件 | 作用 | 进推理？ | 形态 |
|---|---|---|---|
| RC（Rubric Compiler） | `score_steps` → 每任务 BT；前置/后置条件、retry/fallback | 是 | 确定性代码 |
| PCP（Phase-Conditioned Policy） | 单一 VLA；相位 token + FiLM；输出 action chunk | 是 | 唯一学习模型 |
| STG（Spatiotemporal Guard） | 完成 c、进度 p、回归 r、扰动 d、目标存在 o | 是 | 同一 checkpoint 的辅助头 |
| BTR（BT Runtime） | tick、前置检查、后置检查、前进/重试/回溯/恢复、180s 守卫 | 是 | 确定性代码 |
| RF-BC | 评分步骤分段、失败段过滤、相位重加权 | 否 | 离线数据引擎 |
| RDE | 官方 human 备注 → undo→recover 数据 + `RECOVER` 相位 | 否 | 离线数据引擎 |
| PGL/OPT/SVL | 放置目标阶梯、少样本位姿迁移、落点校验 | 是 | BT 叶子/fallback |
| ToC（Tree-of-Chunks） | 关键步采样 K 个 chunk，守卫打分选优 | 可选 | 测试时算力 |
| L2L / DebugLoop | 实验室数据、平台调试槽 | 否 | 流程 |

### 0.3 预期收益（可证伪）

- 主要目标：**总平均成功率 +5pp**；步骤分不显著下降（用于平局）。
- 机制目标：近失 episode 恢复率 ≥20%；人为干扰任务的恢复成功率 ≥50%；完成检测 F1 ≥0.85。
- 统计现实：320 次计分 trial，若 p≈0.3，二项 SE≈2.6pp，95% 区间约 ±5pp。**+5pp 是目标，不是保证**；用 32 任务配对 bootstrap 和调试槽做 go/no-go，不靠单轴小样本。
- 可证伪点：若离线步骤级诊断显示失败主要是空间 grounding，而不是完成检测/恢复，则回退第 7 轮 PGL/OPT；若 BT 恢复在调试槽不能把近失转成成功，则砍掉 BT 恢复，只保留相位条件化。

### 0.4 与第 7 轮（PILOT-GPR）的关系

| 关系 | 内容 |
|---|---|
| 保留 | WLA-1.0-Base 底座、GPR-VLA 目标残差/可逆信念、TLE/ACP/GF 数据引擎、PGL/OPT/SVL 放置子技能、L2L、DebugLoop、安全组件 |
| 升级 | SSG 线性步骤图 → **CHRONO-BT**；SVL → BT 后置条件/fallback；NRB → **RDE**；ICR → 可选目标上下文；按步骤权重重试 → **成功率先行重试** |
| 新增 | PCP 相位条件策略、STG 多时间尺度守卫、RF-BC 评分表过滤 BC、BTR 运行时、ToC 可选测试时算力 |
| 降级 | ICR 主回路、TCLB、FLEET |
| 纠正 | 第 7 轮“排名=成功率与步骤分综合排序”改为“成功率优先，步骤分平局裁判” |

## 1. 事实核对（本轮新增，全部一手；来源表见 §12）

### 1.1 排名规则：成功率优先，步骤分只是平局裁判

官方参赛手册（中/英）明确：

> “实时榜单按 32 个任务的 **总平均成功率** 进行排序，成功率相同时按 **总平均步骤分** 排序，若仍相同，则提交日期较早的模型排序靠前。”[S1][S2]

同手册确认：

- 每个任务 **10 次独立运行**；5 种泛化类型（位置、干扰物、桌面背景、未见物品、人为干扰）**各出现 2 次**。[S1][S2]
- 单次真机执行上限 **180 秒**，超时记失败，并按执行情况计算步骤分。[S1][S2]
- 必须是 **单一模型** 完成全部 32 个任务；不得按任务混用多个模型；模型类型不限。[S1][S2]
- 另有 **不计分的单任务调试通道**，结果不进排行榜。[S1][S2]

这条规则直接改变优化目标：**success rate 是主目标，step score 是 tie-break**。第 7 轮把步骤分当“第二目标”甚至“预算分配依据”是过度设计；步骤分只在成功率打平时兑现。

### 1.2 纠正第 7 轮的评分公式

第 7 轮写的是：

```text
排名 = 成功率与步骤分综合排序
```

应改为：

```text
排名主键 = 32 任务总平均成功率
排名次键 = 32 任务总平均步骤分（仅平局）
排名次次键 = 提交日期（更早优先）
```

于是：

| 第 7 轮说法 | 本轮修正 |
|---|---|
| 终局放置占 39.8% 步骤分，所以是第一目标 | 终局放置是 32/32 任务的 **success 闸门**，所以仍是第一目标；39.8% 只是诊断，不是目标函数 |
| 按步骤权重分配重试预算 | 按“剩余时间 × 当前步成功概率”分配；步骤分只在平局时考虑 |
| 成功率与步骤分综合排序 | 成功率优先；步骤分只在平局时使用 |
| 3200 分是总分 | 3200 是评分表满分之和，用于诊断；不是排行榜的加权目标 |

### 1.5 提交接口 v2 的约束与自由度

`unibot_submission` README（v2，最近提交 2026-08-21）给出：[S9]

- 观测：4 路 RGB（左右高位 + 左右腕部，480×640）、双臂关节/EE 位姿（base 系）、夹爪开度、下半身、`observation.language` 单字符串（整段 episode 不变）。
- `obs_delta_indices`：声明传哪些键、每键堆叠几帧；`image_resize`：每路分辨率；`action_chunk_size`：自定。
- 动作空间：joint 或 ee 二选一，互斥；`reset()` 每 episode 调用；token 双处校验。
- 这意味着我们完全控制推理侧的观测裁剪、时序堆叠、图像缩放、chunk 长度；在观测里做历史堆叠、在 action chunk 上做 BT 触发重规划，都是接口内允许的。

### 1.6 榜单仍是占位，不能当真实排名

截至 2026-10-24：

- `leaderboard.html` 已能渲染 8 个模型，页面显示榜首成功率约 **29.7%**，与“不到 30%”的观察一致。[S5]
- 但 `leaderboard_data.json` 仍写 `"generated_from": "gen_leaderboard.py"`，8 个模型 × 32 任务的 task_metrics 是脚本生成；详情页视频仍为“测试视频占位”；`runs.html` 仍偏占位。[S6][S7]
- 因此这些数字只能当 **难度先验/头部方案类型**，不能当真实排名或轴级瓶颈证据。

## 2. 失败模型：为什么榜首不到 30%

### 2.1 头部方案原型（按公开论文归类，不按占位榜排名）

| 原型 | 代表公开工作 | 强项 | 对 CHRONO-BT 的启示 |
|---|---|---|---|
| Action Reasoning VLA | MolmoAct2：MolmoER 空间/具身推理、OpenFAST、flow-matching 动作专家；强调部署延迟与开放权重 [S27] | 空间 grounding、动作推理 | 语义/空间不是唯一瓶颈；缺持久任务状态与恢复，推理延迟要控 |
| MoT 预训练 VLA | WALL-OSS-0.5：4B、VL Expert + Action Expert、20+ 形态、百万级轨迹、梯度桥接 co-training [S28] | 大规模预训练、零样本可执行性 | 静态策略；需要相位状态、完成验证、失败恢复 |
| World Action Model | DreamZero：14B 视频扩散骨干、联合视频/动作、7Hz 实时闭环 [S29] | 物理动力学、少样本泛化 | 强动力学可做教师/辅助，但 14B/7Hz 不适合作为唯一实时控制器；无符号保证 |
| 高层子任务 VLA | π0.5：异构 co-training、高层语义子任务预测 + 低层动作 [S30] | 开放世界泛化、长程语义 | 高层是学出来的，会漂移；用公开评分表编译的 BT 替代测试时高层推断 |
| World-model 数据 + CoT | GigaBrain-0：world-model 生成数据、RGBD、embodied CoT [S31] | 数据缩放、空间/长程推理 | 合成数据有 sim2real gap、CoT 延迟；我们用真实 33k + 评分表结构，不靠合成数据堆量 |
| 双系统 VLA | GR00T N1.5：Eagle VLM + DiT flow matching、冻结 VLM、grounding [S32] | 语义 grounding、模块化 | 冻结 VLM/无显式记忆；加历史/守卫/BT 恢复 |
| 高效 VLA | DM0：embodied-native、三阶段、flow matching [S33]；Spirit-v1.5：Qwen3-VL + DiT [S35] | 多形态统一、三阶段训练 | 适合做底座；但仍需相位/完成/恢复层 |

**共性**：这些模型都在“看懂 + 动作生成”上很强，但都把“当前第几步、这一步完成了吗、被撤销了吗、失败了怎么回退”留给隐式策略。排行榜 <30% 的成功率，和这个结构性缺口一致。

### 2.2 四类失败（F1–F4）与证据

| # | 失败模式 | 表现 | 证据 | 对策 |
|---|---|---|---|---|
| F1 | 相位/状态别名 | 相似画面在不同阶段输出相同动作；拉链拉开后继续“拉”、碗被拿走后继续“叠” | PHASER 的 state aliasing 分析；T27/T19/T14 的 human 备注 [S19][S4] | PCP 相位条件化 + STG 回归检测 |
| F2 | 复合误差/开环失稳 | 长 chunk 执行到后段偏了也不改；接触后误差放大 | Action chunking 的复合误差/隐式集成；Open-Loop 的反应性；BC 稳定性 [S16][S17][S18] | 中等 chunk + 历史 + BT 触发重规划 |
| F3 | 完成检测/终局验证缺失 | 手松开了但物体没放稳；插头只顶在门口；拉链没拉合 | SeqVLA 的完成头；CycleVLA 的进度/失败预测；SVL 的 settle-verify [S20][S21] | 后置条件 + STG 完成/稳定性 + 重试 |
| F4 | 扰动/撤销后不恢复 | 人把目标移走/把已完成步骤撤销，策略继续原计划 | VLM+BT 的 reactive failure handling；BT-Agent 的结构化失败反馈；Foresight 的失败检测 [S24][S25][S26] | BT backtrack + RDE recover 相位 |

四类失败里，F1/F3/F4 都直接吃“评分表 + 守卫 + BT”，F2 吃“行为克隆的结构化数据 + 短 chunk 重规划”。这就是三个灵感词的交汇点。

### 2.3 为什么不是“再大一点”

- 头部模型已经很大：DreamZero 14B、WLA 6B、WALL 4B、MolmoAct2 4B 级；再大一倍，延迟/部署成本先爆炸，而 180s 真机评测对延迟敏感。
- 官方数据只有 33k/169h；在固定数据上，单纯增大模型容易过拟合任务外观，不一定提升扰动恢复。
- 成功率优先的评测里，**恢复是“乘性”收益**：只要把后续步骤救回来，整题从 0 变 1；而单纯提升动作精度是“加性”的，边际收益递减。
- BT/相位条件是 **数据高效** 的结构注入：不需要新的大规模数据，只需要公开评分表和少量分段标签。

### 2.4 统计现实：320 次 trial 能说明什么

```text
总 trial = 32 任务 × 10 次 = 320
p ≈ 0.3 → SE = sqrt(0.3×0.7/320) ≈ 2.6pp
95% CI ≈ ±5.1pp
每轴 trial = 32 任务 × 2 次 = 64 → SE ≈ 5.7pp
```

所以：

- 目标定 **+5pp** 是合理的“可观测”门槛，不是“稳赢”门槛。
- 不要用单轴 2 次/任务的样本宣称“某轴解决”；应报告 32 任务配对差异、bootstrap 区间、每任务成功数。
- 调试槽用于机制验证（恢复率、完成检测），不是用来估计排行榜显著性。

## 3. CHRONO-BT 架构

### 3.1 总览

```text
┌──────────────────────── Offline（训练/编译/标注）────────────────────────┐
│ 官方 33k（4 相机 + proprio + EE 位姿 + 5 复述）                           │
│   ├─ RC：score_steps → 每任务 BT（Seq/Retry/Guard/Fallback/Timeout）      │
│   ├─ RF-BC：步骤分段 → 过滤失败/无进展段 → 相位重加权                    │
│   ├─ RDE：human 备注 → undo→recover 对 + RECOVER 相位                    │
│   └─ PGL/OPT：放置目标阶梯/少样本位姿库（第 7 轮保留）                    │
└──────────────────────────────────────────────────────────────────────────┘
                                   │
┌──────────────────────── Inference（单一 checkpoint）─────────────────────┐
│ obs：4 RGB + proprio + 夹爪 + 语言 + 历史（短/长/4D 对象记忆）            │
│        │                                                                 │
│        ├─► STG：c（完成）/p（进度）/r（回归）/d（扰动）/o（目标存在）     │
│        │                                                                 │
│        └─► PCP：π_θ(a_chunk | h_t, l, z_s, g_s)                         │
│                          │                                               │
│                          ▼                                               │
│ BTR：Pre → Leaf → Post → advance / retry / backtrack / recover            │
│      180s 时间守卫；关键步 ToC（K=2-4）                                   │
└──────────────────────────────────────────────────────────────────────────┘
```

### 3.2 RC：Rubric Compiler（评分表 → 行为树）

**输入**：

- `info.json` 的 `score_steps`（步骤文本 + 分值）、`scoring_points`（更细中文）、`difficulty`。
- `meta/tasks.parquet` 的 5 条英文复述（语言匹配）。
- 第 7 轮的表 A/表 B（已抓全 32 任务；本轮继续用）。

**节点类型**：

```text
Seq(children)            顺序执行；任一失败则失败
Sel(children)            依次尝试；任一成功则成功
Retry(k, child)          最多重试 k 次
Guard(pred, child)       前置/后置条件；不满足则失败
Leaf(skill, phase)       调用 PCP；phase=步骤 ID 或 RECOVER
Fallback(primary, ...)   主方案失败后的恢复候选
Timeout(τ, child)        单步/整题时间预算
```

**编译规则**：

1. 每个 `score_step` → 一个 `Step_i = Retry(k_i, Seq(Pre_i, Leaf_i, Post_i))`。
2. 任务整体 → `Seq(Step_1, ..., Step_S)`，外层 `Timeout(180s, ...)`。
3. 放置/插入/闭合类步骤 → 加 `Fallback(Leaf_i, Recover_i, Backtrack_{i-1})`。
4. 终局步骤 → 加 `Retry(3, ...)` + settle-verify 后置条件（SVL 遗产）。
5. `Pre_i`/`Post_i` 由谓词库生成：`on_table`、`on_top`、`in_container`、`inserted`、`closed`、`zipped`、`hanging`、`poured`、`upright` 等；不确定的谓词交给 STG。
6. 指令匹配：5 条复述精确匹配 + 规范化（小写/去标点）+ 嵌入兜底；匹配到任务后加载对应 BT。

**T27 示例**（StackBowls，30/30/40）：

```python
BT_T27 = Seq([
    Retry(2, Step(
        pre  = table_clear(),
        leaf = Leaf("place bowl1 in the middle", phase=1),
        post = on_table("bowl1", "middle"),
    )),
    Retry(2, Step(
        pre  = on_table("bowl1", "middle"),
        leaf = Leaf("stack bowl2 onto bowl1", phase=2),
        post = on_top("bowl2", "bowl1"),
    )),
    Retry(3, Fallback([
        Step(
            pre  = on_top("bowl2", "bowl1"),
            leaf = Leaf("stack bowl3 onto bowl2", phase=3),
            post = on_top("bowl3", "bowl2"),
        ),
        Recover("regrasp bowl3 and re-stack", phase="RECOVER"),
        Backtrack(to=2),
    ])),
])
```

**T10 示例**（PlugCharger，30/30/40）：

```python
BT_T10 = Seq([
    Retry(2, Step(pre=table_clear(), leaf=Leaf("grab power strip", 1), post=held("strip"))),
    Retry(2, Step(pre=held("strip"), leaf=Leaf("grab plug", 2), post=held("plug"))),
    Retry(3, Fallback([
        Step(pre=held("plug"), leaf=Leaf("plug into power strip", 3), post=inserted("plug", "strip")),
        Recover("align plug to socket and re-insert", phase="RECOVER"),
        Backtrack(to=2),
    ])),
])
```

**为什么不是 LLM 规划器**：任务分解已经公开；测试时 LLM 增加延迟/幻觉/合规风险。RC 是离线编译，BT 是确定性代码，PCP 是唯一学习模型。

### 3.3 PCP：Phase-Conditioned Policy（相位条件化策略）

**底座**：

- 首选 **WLA-1.0-Base 6B**（Unitree 原生、Apache-2.0、24GB 可微调）[S34]；若 p99 延迟不达标，换 **GR00T N1.5 / π0.5** 这类 3B 级底座作为对照。[S30][S32]
- 方法不绑定底座；报告里以 WLA 为主，3B 为延迟/成本消融。

**输入**：

```text
h_t      = 多时间尺度历史（见 3.4）
l        = 指令（5 条复述之一）
z_s      = 相位嵌入：task_id + step_id + step text 的编码
g_s      = 目标上下文：PGL 的锚点/OPT 的 6D 位姿（可选）
```

**输出**：

```text
a_{t:t+H} = π_θ(h_t, l, z_s, g_s)，H=16（约 1s @15Hz）
```

**相位条件化**：

- 语言侧加 **phase token**（可学习嵌入或 step text 编码）。
- 动作专家中间层加 **FiLM**：`h' = γ(z_s) ⊙ h + β(z_s)`。
- PHASER 的消融显示 FiLM 优于 token-level conditioning（在他们的变形物任务上）；我们在 action expert 上用 FiLM，在语言侧保留 phase token，做 A/B。[S19]
- 关键：相位嵌入是 **任务/步骤共享** 的，不是 per-task 模型；同一 checkpoint 服务全部 32 任务。

**训练目标**：

```text
L = L_flow + λ_c L_completion + λ_p L_progress + λ_r L_regression
    + λ_d L_disturbance + λ_o L_object + λ_g L_goal
```

- `L_flow`：flow matching / diffusion 动作损失。
- `L_completion`：当前步完成 BCE。
- `L_progress`：阶段内进度回归（0–1）。
- `L_regression`：进度下降/后置条件 1→0 的 BCE。
- `L_disturbance`：人为干扰/目标位移 BCE。
- `L_object`：目标存在/3D 位置辅助损失（可选）。
- `L_goal`：PGL/OPT 目标上下文一致性（可选，低权重）。

**为什么相位条件化能帮 BC**：

- 解决 state aliasing：同一视觉观测在不同相位输出不同动作。
- 共享动作动力学：所有阶段共享底层技能，只调制高层特征；比 per-task/per-step 模型数据效率高。
- 让 BT 的 `phase` 成为策略输入，而不是隐式猜测；BT 前进/回退时，策略行为随之切换。

### 3.4 STG：Spatiotemporal Guard（时空守卫）

**输入**：

| 时间尺度 | 内容 | 用途 |
|---|---|---|
| 短（1s @30Hz） | 4 RGB + proprio + 夹爪 + EE 速度 | 接触、滑动、放置稳定性 |
| 中（5s @5Hz） | 下采样 RGB + EE 轨迹 | 步骤过渡、动作是否卡住 |
| 长（20s @2Hz） | 关键帧 + 对象轨迹 | 对象永久性、进度回归、人为扰动 |
| 4D 对象记忆 | 任务相关物体的 3D 框/关键点，最近 20s | “目标还在不在/被移到哪” |

**头**：

```text
STG(h_t, s) → (c_t, p_t, r_t, d_t, o_t)
c_t ∈ [0,1]   当前步完成概率
p_t ∈ [0,1]   任务进度（(s-1+within)/S）
r_t ∈ [0,1]   回归/撤销概率（p 下降或 post 1→0）
d_t ∈ [0,1]   人为扰动/目标位移概率
o_t ∈ [0,1]   目标存在/可见概率
```

**标签**：

- `c_t`：由 RF-BC 的步骤边界给出；边界后为正，边界前为负。
- `p_t`：步骤索引 + 阶段内视觉变化/时间规整；参考 SARM/ProcVLM 的 progress 监督。[S22][S23]
- `r_t`：官方 human 备注的 undo 剧本 + 合成“完成后撤销”片段。
- `d_t`：合成目标平移/遮挡 + 官方备注。
- `o_t`：目标检测/跟踪伪标签（离线），人工抽检。

**架构**：

- 在 VLA 的视觉/proprio token 上加一个轻量时序 Transformer（2–4 层），多尺度 token 拼接；输出上述头。
- 与 PCP 联合训练；STG 头共享 VLA 主干，不引入第二个大模型。
- 推理时只跑一次 forward，STG 头和动作头同时输出；避免额外 VLM 调用。

**校准**：

- 温度缩放 + conformal prediction（参考 Foresight 的 FCP）校准阈值。[S26]
- 滞回：`c_t > τ_high` 才前进；`c_t < τ_low` 才回退；中间区域继续执行/观察，避免抖动。
- 误判兜底：确定性谓词（夹爪开合、EE 位姿、物体在容差内）优先；STG 只在不确定时投票。

### 3.5 BTR：BT Runtime（运行时）

```python
def run(task, obs_stream, policy, stg, bt, deadline=180.0):
    s = 0
    t0 = now()
    backtracks = 0
    while s < len(bt.steps) and now() - t0 < deadline:
        obs = obs_stream.latest()
        c, p, r, d, o = stg(obs.history, s)

        if r > TAU_R or d > TAU_D:
            s = bt.backtrack(s, obs)          # 回到受影响的步骤
            backtracks += 1
            continue

        if not bt.pre(s, obs):
            s = bt.repair_pre(s, obs)         # 重新感知/重抓/复位
            continue

        if c > TAU_C_HIGH and bt.post(s, obs):
            s += 1                            # 完成，前进
            continue

        if deadline - now() < RESERVE:
            bt.conservative(s)                # 时间不够：保守完成当前步

        chunk = policy.act(obs.history, obs.language, phase=s, goal=bt.goal(s))
        execute(chunk)

        if bt.post(s, obs):
            s += 1
        elif c < TAU_C_LOW:
            bt.retry(s)                       # 没有进展：重试/换候选
        if backtracks > MAX_BACKTRACK:
            break
    return s == len(bt.steps)
```

**恢复策略**（按代价从低到高）：

1. **Re-perceive**：移动头部/腕部相机，重新检测目标。
2. **Regrasp**：松开、重新抓取（保持当前步）。
3. **Nudge/Push**：轻推/轻压/旋转，修复放置姿态。
4. **Backtrack**：回到上一步，重新执行（用于 undo/目标被移走）。
5. **Re-plan**：在 BT 的 fallback 里换候选（直接放→重抓→推正→回退）。

**时间守卫**：

- 总预算 180s；预留 10–15% 给最终验证/安全停。
- 成功率优先：时间不够时，优先完成当前步/整题，不为了部分分做高风险动作。
- 长程任务（T16/T17/T31）限制 backtrack 次数；短任务（T27/T10）允许更多重试。
- 每次 retry 记录“为什么失败”，作为下一轮 RF-BC 的困难样本。

**ToC（可选）**：

```python
if s in CRITICAL_STEPS:                  # 终局放置/插入/闭合
    cands = [policy.sample(history_window=w) for w in (1s, 5s, 20s)]
    best = argmax([stg.score(c, s) for c in cands])
    execute(best)
else:
    execute(policy.act(...))
```

K=2–4，只在关键步开；用 STG 的完成/稳定性打分，不引入额外模型。

### 3.6 RF-BC：Rubric-Filtered Behavior Cloning

**目标**：把 33k 演示从“整段动作克隆”变成“按评分步骤分段、去失败段、相位平衡”的训练数据。

**分段**：

1. 用夹爪开合、EE 速度极小值、物体位姿突变、视频变化点做初始边界。
2. 用 `score_steps` 的步骤文本 + 5 条复述做语义对齐；用 DTW 把演示进度对齐到步骤序列。
3. 每任务人工抽检 10–20 条；边界 F1 不达标的任务改用手工模板。
4. 产出：`(episode, phase, start, end, success, p_t)`。

**过滤/重加权**：

- 去掉整段失败/无进展的 episode（若成功标签可用）。
- 去掉 `p_t` 长期不增的 chunk（卡住/犹豫段）。
- 相位重加权：稀有相位（终局插入/闭合/倒药）加权；简单抓取降权。
- 难度重加权：Hard 任务的终局步加权；但不按步骤分值加权（分值只用于诊断/tie-break）。
- 保留自然重试段：它们是恢复行为的正样本，不要全过滤。

**数据量估计**：

- 33k episodes × 3–5 步 ≈ **10–15 万相位段**（需实际统计）。
- 恢复对：优先 8–12 个有 human 备注的任务，目标 5k–10k 对。
- 扰动/背景增强：5k–10k 段；默认只用官方数据 + 轻量增强，不引入外部数据。

### 3.7 RDE：Recovery Data Engine（官方备注 → 恢复数据）

**输入**：`info.json` 的 `human_1_note`、`human_4_note`、`unseen_object_3`。[S4]

**构造**：

1. 选一个成功 episode，找到步骤边界。
2. 按备注在边界后施加 1-DOF 平移/移除/打开（如 T27 叠完第二个后拿走 bowl2）。
3. 从扰动后的状态开始，执行“恢复→继续”轨迹；若没有真实恢复数据，用仿真/回放 + 脚本生成，或让遥操作补采少量。
4. 打上 `RECOVER` 相位标签；训练 PCP 在 `RECOVER` 相位输出“回到上一步/重新放置”的行为。
5. BT 在 `r_t`/`d_t` 高时触发 `RECOVER` 叶子。

**优先级**：

- P0：T10、T14、T17、T19、T26、T27（备注明确、终局关键）。
- P1：T16、T18、T23、T28、T29、T31（闭合/拉链/装箱）。
- P2：其余任务用通用扰动（平移/遮挡/拿走后放回）。

**风险**：官方备注编号含义未核实；合成扰动可能有 sim2real gap。缓解：真实备注优先、通用扰动兜底、少量真机调试槽验证。

### 3.8 单模型合规

- **一个 checkpoint**：VLA 主干 + phase embedding + STG 头 + action expert；没有 per-task 权重、没有第二个 VLM/LLM。
- **确定性代码**：RC、BTR、PGL/OPT 的几何计算是代码；不是学习模型。
- **离线数据**：RF-BC/RDE/检索库是数据，不是推理模型。
- **披露**：模型卡写清楚辅助头、BT 代码、数据来源、外部数据开关。
- **退路**：若主办方认为辅助头/任务特定 BT 代码越界，去掉 STG 头（用确定性谓词）或把 BT 退化为通用模板 + 评分表数据；PCP 仍是唯一模型。

## 4. 形式化

### 4.1 任务与相位

任务 `T` 有 `S_T` 个评分步骤。相位 `s ∈ {1,...,S_T} ∪ {RECOVER}`。每个相位有：

- 叶子策略 `π_θ(a_{t:t+H} | h_t, l, z_s, g_s)`
- 前置条件 `Pre_s(o_t)`
- 后置条件 `Post_s(o_t)`
- 重试次数 `k_s`

### 4.2 行为树

```text
B_T = Seq(Step_1, ..., Step_{S_T})
Step_s = Retry(k_s, Seq(Guard(Pre_s), Leaf(π_θ, z_s), Guard(Post_s)))
```

放置/插入步加 `Fallback(Step_s, Recover_s, Backtrack_{s-1})`。

### 4.3 成功与目标

```text
success = ∏_{s=1}^{S_T} 1[Post_s(o_{t_s})]
```

优化目标：

```text
max_θ  E[success]     # 主目标
s.t.   T_episode ≤ 180s
tie-break: E[step_score]
```

注意：这不是“步骤分加权和”；步骤分只在 success 打平时使用。

### 4.4 守卫与转移

```text
g_φ(h_t, s) = (c_t, p_t, r_t, d_t, o_t)
```

BT 转移：

```text
if r_t > τ_r or d_t > τ_d:      s ← Backtrack(s)
elif not Pre_s:                 s ← RepairPre(s)
elif c_t > τ_c and Post_s:      s ← s + 1
else:                           execute π_θ(· | s)
```

### 4.5 为什么是 options/BT，而不是普通状态机

- 每个 `Step_s` 是一个 option：initiation set = `Pre_s`，policy = `π_θ(·|z_s)`，termination = `Post_s` 或超时。
- BT 的组合子（Seq/Sel/Retry/Fallback）提供结构化的失败语义；普通状态机难以表达“先直接放，失败则重抓，再失败则推正，再失败回退”的优先级。
- BT 的局部检查可以在不调用大模型的情况下中止错误动作（BT-Agent 的证据）。[S25]

## 6. 数据引擎细节

### 6.1 分段标签

- 夹爪事件：open/close 转变；抓取/释放点。
- EE 速度：局部极小/停顿；接触前后。
- 物体位姿：目标物体相对容器/桌面的位姿突变。
- 视频变化：帧差/光流峰值；阶段边界。
- 语义：`score_steps` 文本 + 5 复述；DTW 对齐。
- 人工：每任务 10–20 条抽检；Hard 任务全检。

### 6.2 进度标签

```text
p_t = (s - 1 + within_s(t)) / S
within_s(t) = 视觉变化/时间规整的阶段内进度（0–1）
```

参考 SARM 的 stage-aware reward 和 ProcVLM 的 procedure-grounded progress；但我们只把 progress 当 **运行时守卫**，不当 RL reward。[S22][S23]

### 6.3 恢复标签

- 官方备注：平移/撤销/打开/拔起。
- 合成：在成功 episode 的步骤边界施加扰动，记录恢复。
- 负样本：扰动后未恢复的片段。
- `RECOVER` 相位：训练策略“回到上一步/重新放置/重新插入”。

### 6.4 数据质量

- 去掉失败/无进展段；保留自然重试段。
- 相位平衡：终局/插入/闭合过采样；简单抓取降采样。
- 语言：5 条复述全覆盖；训练时随机采样一条，避免只记一条。
- 背景/位置：官方 5 轴数据已覆盖；不做过度合成，避免 sim2real gap。

## 7. 评测协议

### 7.1 离线诊断

| 指标 | 目标 | 数据 |
|---|---|---|
| 相位边界 F1 | ≥0.80 | 留出 episode，人工抽检 |
| 完成检测 F1 | ≥0.85 | 边界前后帧 |
| 进度 MAE | <0.08 | 留出 episode |
| 回归/undo AUC | ≥0.85 | 合成 undo + 官方备注 |
| 扰动检测 AUC | ≥0.80 | 合成平移/遮挡 |
| 目标存在 F1 | ≥0.90 | 跟踪伪标签 |

离线只做诊断；闭环必须上真机调试槽/仿真。

### 7.2 闭环

- **仿真/回放**：`unitree_sim_isaaclab` 可用时，在 8 个任务上做 BT vs flat 的 A/B；没有高保真资产的任务不做强结论。[S36]
- **调试槽**（不计分单任务）[S8]：T27（堆叠）、T10（插入）、T19（拉链+undo）、T17（多步+undo）；每任务 5–10 次；比较 flat VLA / +PCP / +STG / +BT。
- **正式计分跑**：32×10；主指标 success rate；次指标 step score；按轴描述性分析，不做小样本显著性断言。

### 7.3 统计

```text
primary: 32 任务平均成功率
secondary: 32 任务平均步骤分（仅平局）
uncertainty: 任务级 paired bootstrap（10k 次）
target: +5pp；报告 95% CI
per-axis: 64 trial，SE≈5.7pp；只做描述，不做强断言
```

## 9. 创新点清单（持续迭代）

> 状态：押注=本轮主线；升级=旧点改造；保留=沿用；降级=保留但非主回路；砍=不做。

### I1 CHRONO-BT：评分表编译的运行时行为树（升级 SSG，押注）
- 动机：官方 `score_steps` 是免费、与评测同构的步骤级结构；BT 提供前置/后置、retry、fallback、backtrack。
- 差异：不是 LLM 规划器，也不是手写技能树；由公开评分表编译，叶子是单一 VLA。
- 可行性：32 个 `info.json` 已抓全；BT 是确定性代码；1 人周。
- 资源：CPU；无额外数据。
- 步骤：解析 → 谓词模板 → BT → runtime → 调试。
- 风险：任务特定代码合规性 → 通用模板退路。
- 状态：**押注**。

### I2 PCP：相位条件化的单一 VLA（新增，押注）
- 动机：state aliasing 是长程 BC 的结构性失败；相位标签免费。
- 差异：phase token + FiLM；一个 checkpoint 服务全部任务/阶段；不是 per-task LoRA。
- 可行性：WLA/GR00T/π0.5 均可加；LoRA + action expert。
- 资源：8×H100 3–5 天。
- 步骤：分段 → 相位嵌入 → FiLM → 联合训练 → 消融。
- 风险：相位标签噪声 → 人工抽检/降粒度。
- 状态：**押注**。

### I3 STG：多时间尺度时空守卫（新增/升级，押注）
- 动机：完成检测不够；还需要进度、回归、扰动、目标存在。
- 差异：短/中/长 + 4D 对象记忆；同一 checkpoint 辅助头；不是第二个 VLM。
- 可行性：VLA token + 轻量时序 Transformer；标签可自动生成。
- 资源：1–2 天训练；推理 <10ms。
- 步骤：标签 → 头 → 校准 → 消融。
- 风险：误报 → 滞回/conformal/确定性兜底。
- 状态：**押注**。

### I4 RF-BC：评分表过滤的行为克隆（新增，中高）
- 动机：33k 整段灌入会学到失败/停顿/无进展先验。
- 差异：按评分步骤分段、去失败段、相位重加权；保留自然重试。
- 可行性：夹爪/EE/物体/视频事件 + 少量人工抽检。
- 资源：CPU/GPU 数据管线 2–3 天。
- 步骤：分段 → 过滤 → 重加权 → 训练。
- 风险：分段错误 → 任务级回退。
- 状态：**主回路**。

### I5 RDE：官方备注恢复数据（升级 NRB，中高）
- 动机：human 备注是人为干扰轴最具体的剧本；undo 是主要失败。
- 差异：从“训练数据”升级为“BT 触发 + RECOVER 相位 + 恢复对”。
- 可行性：备注明确；仿真/回放可合成；少量遥操作补采。
- 资源：1–2 人周；优先 8–12 任务。
- 步骤：备注表 → 扰动脚本 → 恢复对 → 微调。
- 风险：sim2real gap → 真实备注优先/调试槽验证。
- 状态：**主回路**。

### I6 ToC：关键步 Tree-of-Chunks（新增，可选）
- 动机：终局放置/插入是关键步；采样多个 chunk 可提升稳健性。
- 差异：K=2–4，只在关键步；用 STG 打分；不是全局 MCTS。
- 可行性：推理侧多次采样；延迟可接受。
- 资源：2–4× 计算，仅关键步。
- 步骤：候选生成 → 守卫打分 → 执行最优。
- 风险：延迟 → 只在终局/插入开。
- 状态：**可选**。

### I7 PGL/OPT/SVL：放置子技能（保留）
- PGL 目标阶梯、OPT 少样本位姿迁移、SVL settle-verify 作为 BT 叶子/fallback；不再单独做主回路。
- 状态：**保留**。

### I8 GPR-VLA + WLA 底座（保留）
- 目标残差/可逆信念与 BT 的相位/恢复天然对齐；WLA 6B 为主，3B 为延迟对照。
- 状态：**保留**。

### I9 L2L / DebugLoop（保留，工程）
- 实验室数据协议 + 平台调试槽；默认外部数据 OFF。
- 状态：**保留**。

### I10 ICR（降级）
- 检索上下文从主回路降为可选目标上下文；避免延迟和“复制动作”风险。
- 状态：**降级**。

## 13. 开放问题

1. “总平均成功率”是 32 个任务成功率的算术平均，还是 320 次 trial 的 pooled 成功率？两者在 10 次/任务下接近，但置信区间算法不同。
2. 步骤分聚合公式：按 episode 部分分平均？取最好？是否按任务等权？
3. 外部数据（自采/实验室）与预训练权重（含论文方法）是否允许？——已读手册未明确，需邮件确认。
4. 单模型定义边界：同一 checkpoint 的辅助头、确定性 BT 代码、评分表编译的任务逻辑，是否需在模型卡披露/是否被视为“多模型”？
5. 不计分单任务调试的可用次数/成本/泛化条件是否随机？
6. 评测语言是 5 条英文复述之一，还是中文/未见复述？PCP 的语言泛化需要知道。
7. `human_1`/`human_4`/`unseen_object_3` 的编号是轴编号还是试次编号？评测是否按这些剧本采样？
8. 是否允许任务特定代码（BT）？若不允许，通用 BT 模板 + 评分表数据是否可接受？
9. 官方是否提供 32 任务的仿真资产/评测脚本？这决定闭环 A/B 的可信度。
10. 真实榜单发布后，重跑“成功率优先/近失恢复”假设，替换占位先验。

## 14. 一句话押注

**把公开评分步骤编译成运行时行为树，用相位条件化的单一 VLA 做树叶、用多时间尺度 4D 历史学习每一步的完成/回归/扰动守卫，并把重试预算全部押在“把近失转成完整成功”上——这是在不增大模型的前提下，同时打穿成功率闸门和人为干扰轴的最短路径。**
