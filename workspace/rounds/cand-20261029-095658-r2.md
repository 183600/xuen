# 第 2 轮（新循环；总第 13 轮）· REFER-SERVO：先把语言指对，再把目标跟住，最后把 3 厘米伺服住

> 检索/复核日期：**2026-10-29（UTC）**。赛事身份已再次核实：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。不是 PLM UniBot，也不是 OpenUniBot。本轮是灵感循环第 2 轮，三个词是「语音交互」「抗干扰」「视觉伺服」。本轮不推倒第 12 轮 CHUNK-SERVO，而是给它补上缺失的前置层：**先把语言指代锚定对（RAG），再把目标身份跟住（IPAT），然后用锚相对 5 步视觉伺服补最后 3 厘米（ARS），最后用重锚定恢复抗人为干扰（RAR）**。语音在本赛题里不是音频通道，而是“同义改写 + 指代消歧”的离线压力测试。

## 0. 本轮思考轨迹（先给过程，再给结论）

1. **先核赛事身份。** 官网标题、挑战页、规则文档、提交仓库都指向宇树 UniBot 世界挑战赛；G1 + Dex1、32 个桌面任务、单模型、远程 API，与用户所指一致。没有发现第二个同名赛事更匹配。
2. **再核规则与 API。** 重新读了挑战页和提交模板：四路 RGB、无深度/力/触觉/音频；`observation.language` 是固定字符串、全程不变；`action_chunk_size` 固定且 chunk 内开环执行；EE 动作是 base 系绝对位姿；每次 `get_action` 必须带 token。
3. **再核榜单。** 上一轮看到页面“Coming Soon”，本轮用 `r.jina.ai` 渲染后发现榜单其实有 8 个预览模型；直接抓取仍被 567 反爬页挡住。`leaderboard_data.json` 仍是 8 个模型、256 条 task metrics。进一步做算术与相关分析，确认这份榜单是**预览/合成数据**，不能当真实 SOTA。
4. **再核数据。** 32 个 HF 数据集共 33,276 episodes / 18,282,246 frames / 169.28h；每个 `tasks.parquet` 的任务串含 **5 条 `@` 分隔的同义改写**；官方 WLA 的 dataloader 会随机抽一条。**腕部彩色相机有内参**（32/32 数据集），上一轮“腕部无内参”的说法是错的；但 API 确实不暴露 IR/深度。
5. **再核头部模型。** MolmoAct2、WALL-OSS、DreamZero、Spirit、DM0、π0.5、GigaBrain、GR00T 的共同点不是“模型不够大”，而是**开环 chunk + 语言表面匹配 + 没有指代身份后验**。榜首不到 30%，说明共享瓶颈在“执行前的指对”和“执行中的跟住”，不只是“执行末端的 3 厘米”。
6. **再搜近期论文。** LIBERO-Para 证明同义改写会让 VLA 掉 22–52pp，且 80–96% 的失败发生在 planning-level task identification；RefGuard 证明身份保持的 grounding 能在场景变化后恢复 86.7%；DRAGON-VLA 证明 7 个干扰物下 object-centric grounding 能到约 80%，而基线 <10%；A-FAR/EATR-Stereo 证明遮挡恢复；SocialVLA 证明 G1 上人的语音/表情会触发 336ms 的 gate-to-hold。它们共同指向一个缺口：**语言指代身份 + 时间身份 + 确定性伺服 + 重锚定恢复，四件事没有在“单模型、无深度、无音频”的约束下被组合过。**
7. **最后收束。** 把“语音交互”翻译成“同义改写下的指代锚定”，把“抗干扰”翻译成“身份保持跟踪 + 重锚定”，把“视觉伺服”翻译成“锚相对的 5 步闭环”。形成 REFER-SERVO。它不是第二个学习模型，而是在 WLA 外面加一层符号锚图、经典跟踪和确定性控制，符合单模型规则。
8. **明确不做什么。** 不做在线 ASR/TTS（无音频、无评分、增延迟）；不做第二个在线大模型（单模型风险）；不做 32 个任务各训一个策略；不做 6D 物体位姿网络（透明/反光/变形不可靠）；不做 30Hz 广域网伺服（RTT 不允许）；不把预览榜单当 SOTA。

## 1. 结论先行：榜首不到 30%，缺的是“指对 + 跟住 + 伺服 + 恢复”的串联

截至 2026-10-29，榜单 JSON 仍返回 8 个模型：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。头尾只差 9.2pp；256 条任务成功率里 255 条不是 10% 的整数倍；`step ~ success` 回归 R² > 0.999999；跨模型任务成功率的平均 off-diagonal 相关只有 0.0975。这三点合起来说明：**这份榜单是预览/合成数据，数字只能当“难度信号”和“预览上限”，不能当真实 SOTA，也不能用来做逐任务过拟合。**

但“榜首不到 30%”这个信号仍然有用：它说明所有模型共享一个执行瓶颈。第 12 轮把它归因为“最后 3 厘米的开环误差”，只对了一半。更完整的成功链是：

```text
P(success) ≈ P(指代正确) × P(抓取正确) × P(搬运正确) × P(对齐/接触正确) × P(受扰后恢复)
```

其中：
- **P(指代正确)**：语言里的“红色积木”“左边的杯子”“带盖的盒子”是否绑定到正确的实例；同义改写、重复实例、干扰物、未见物体都会打穿它。
- **P(抓取/搬运正确)**：VLA 的 30 步 chunk 是否把夹爪带到目标附近；这是现有 VLA 的强项，也是开环误差的来源。
- **P(对齐/接触正确)**：最后 3 厘米的插入、拧、拉、倒、叠；第 12 轮 CHUNK-SERVO 的主战场。
- **P(受扰后恢复)**：人把物体挪走、遮挡、换背景后，策略是否发现“世界变了”并重新绑定；这是 5 类泛化里“人为干扰”轴的核心。

**一句话：一个精确的伺服如果指向了错误的指代，仍然是失败；“先把语言指对，再把目标跟住，最后把 3 厘米伺服住”才是完整闭环。**

| 灵感词 | 赛题里的真实形态 | 可落地动作 | 明确不做 |
|---|---|---|---|
| 语音交互 | 无音频通道；`language` 是固定文本；数据里有 5 条同义改写；WLA 训练随机抽一条 | 离线 32×5 指代锚图；同义改写/ASR/TTS 压力测试；指代消歧 | 在线 ASR/TTS、语音唤醒、对话管理 |
| 抗干扰 | 干扰物、背景变化、未见物体、人为移动/遮挡；都是视觉/物理干扰 | 身份保持跟踪（IPAT）+ 重锚定恢复（RAR）+ 负锚点 | 第二个在线大模型、通用异常检测大网络 |
| 视觉伺服 | 开环 chunk、RTT、最后 3 厘米；四路 RGB，无深度 | 锚相对 5 步 IBVS/PBVS；头双目测深；腕部彩色内参 | 30Hz 广域网伺服、6D 物体位姿网络、力控 |

## 2. 本轮新核实/新纠正的事实

> 证据等级：**A** = 官方文档/官方代码/数据本身可直接验证；**B** = 对官方数据的二次统计或对公开页面的解析；**C** = 第三方论文/博客/推断。所有链接检索日期均为 2026-10-29。

### 2.1 赛事、规则与榜单

- **A｜赛事身份。** 官网 <https://unibot.unitree.com/> 与挑战页 <https://unibot.unitree.com/challenges.html> 明确：宇树 UniBot 世界挑战赛，G1 人形 + Dex1 三指手，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API（检索 2026-10-29）。
- **A｜规则要点。** 单模型；每任务 10 次；5 类泛化各 2 次（位置、干扰物、背景、未见物品、人为干扰）；单次 180s；N 个端口从 8765 起；另有不计分的单任务测试通道；提交仓库 <https://github.com/unitreerobotics/unibot_submission>（检索 2026-10-29）。
- **B｜榜单没有“重置”，只是未渲染时显示 Coming Soon。** 直接抓 `https://unibot.unitree.com/leaderboard.html` 会拿到 567 反爬 HTML，正文显示“Coming Soon”；用 `https://r.jina.ai/https://unibot.unitree.com/leaderboard.html` 渲染后，页面出现 8 个模型和 32 任务热力图。`leaderboard_data.json` 经 `r.jina.ai` 也返回同一批数据。**结论：不要把未渲染的 Coming Soon 当成榜单清空；也不要把渲染出的预览数据当成真实成绩。**
- **B｜榜单是合成/预览。** `leaderboard_data.json` 的 8 个模型、256 条 task metrics 中，255 条成功率不是 10% 的整数倍；`step ~ success` 的线性回归 R² > 0.999999，最大残差 < 0.006；跨模型任务成功率的平均 off-diagonal 相关仅 0.0975。真实 10 trials/task 的成功率只能是 10% 的整数倍，真实任务难度也应产生正相关。**结论：这是 `gen_leaderboard.py` 生成的预览数据，不能当 SOTA，也不能逐任务抄。**
- **B｜runs 页有 256/256 条记录，但详情视频是占位。** 说明系统在跑，但失败分布/视频不可用；无法从榜单反推真实失败模式。
- **B｜模型名以 JSON 为准。** JSON 是 `MolmoAct2`、`WALL-OSS-0.5`、`DreamZero`、`Spirit-v1.5`、`DM0`、`PI-0.5`、`GigaBrain-0`、`GR00T N1.5`；页面显示名略有缩写。写报告时用 JSON 名，避免把 `WALL-OSS-0.5` 写成 `WALLOSS` 造成版本混淆。

### 2.2 API：语音不是通道，语言是固定文本

- **A｜观测。** `observation` 只有四路 RGB：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`，加上本体感觉 `state` 和文本 `language`；**没有 depth、camera_info、force、tactile、audio**（提交模板与 API 文档，检索 2026-10-29）。
- **A｜语言。** `observation.language` 是单个 `str`，不是序列；`language.offset` 必须是 `[0]`；同一 episode 内不变。它不是“每步语音指令”，而是“本 episode 的任务文本”。
- **A｜动作。** `action_chunk_size` 由服务端固定；chunk 内开环执行；执行中不能插队。EE 动作是 base 系绝对 `xyz + rpy`；`joint` 与 `ee` 互斥；`pivot` 是 7 维下肢/高度目标；每次 `get_action` 必须带 `meta.token`。
- **A｜延迟。** 服务端记录 `send_time`/`receive_time`/`server_time`；RTT 是真实存在的，且不同端口/网络会变。**不能假设 30Hz 远程闭环。**
- **推论（B/C）。** 在这个 API 上做“语音交互”只有三条路：① 离线把语音转文本，再把文本当 `language` 用（但评测器不会给你音频，除非你自己加麦克风，且不计分）；② 把数据里的 5 条同义改写当“语音多样性”的代理，做指代鲁棒性；③ 如果同一赛事/周边活动有 Multimodal HRI 赛道，去那里做真正的语音交互，不要把它和 UniBot-V1 的单模型赛道混在一起。**本报告选②，并把①作为可选的演示层，不进入评分路径。**

### 2.3 数据：33k episodes、5 条改写、腕部有内参

- **A｜规模。** 32 个 HF 数据集合计 **33,276 episodes / 18,282,246 frames / 169.28h**（30fps）；每任务 969–1,533 episodes；官方集合页 <https://huggingface.co/collections/unitreerobotics/unibot-v1-challenge-dataset>（检索 2026-10-29）。
- **A｜5 条改写。** 每个 `meta/tasks.parquet` 的 `task` 字段不是单句，而是 **5 条同义改写用 `@` 连接**。例如 `PlugInEthernet` 同时包含“Plug the Ethernet cable into the network port.”及其改写。官方 WLA dataloader 第 515 行 `task = random.choice(item.get("task", "").split("@"))` 每个样本随机抽一条（<https://github.com/unitreerobotics/unifolm-wla/blob/main/src/unifolm_vla/dataloader/lerobot_datasets.py>，检索 2026-10-29）。**这直接证明：语言多样性不是我们臆想的，是官方训练分布的一部分；但“随机抽一条”不等于“学会指代不变性”。**
- **A｜腕部有彩色内参。** 32/32 数据集的 `wrist_left.color.camera_matrix` / `wrist_right.color.camera_matrix` 都存在：fx≈434–437，fy≈434–437，cx≈317–324，cy≈239–243（不同数据集略有差异）。上一轮“腕部没有内参”的说法是**错误**的，本轮修正。
- **A｜腕部 IR 双目存在，但 API 不给。** 腕部 IR 双目基线约 18mm，可用离线标定做近距深度；但 API 只给彩色 RGB，不给 IR/深度。**所以在线只能用“彩色 + 已知物体尺寸/头部双目”补深度，不能假设腕部有深度。**
- **A｜头部双目。** 头部双目已校正，基线 **58.2526mm**，fx≈282.37（以实际 info 为准）；`state_d435` 是头相机在 base 系的位姿；`state_torso` 是躯干位姿。API 不直接给 `state_d435`，但给了 `lower_body`（含腰部）；可用离线运动学/拟合恢复头相机位姿（证据等级 B，需 G0 验证）。
- **A｜pivot 统计。** `action.pivot` 7 维：dim0≈0、dim1≈0、dim2∈[-0.8,0.8]、dim3=0、dim4=0.15、dim5=0、dim6=0.654–0.740（高度）。README 写作 `[vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]`。**第一版可以返回零 pivot 保底，只把 height 映射到当前站姿；不要让 pivot 成为失败源。**
- **A｜EE 位姿。** `state_left_ee_pose`/`state_right_ee_pose` 是夹爪基座在 base 系的位姿；`left_ee_pose_gripper_base` 是夹爪基座；`recomputed_ee_valid` 可用于过滤坏帧。腕部相机到 EE 的外参**数据里没有直接给**，需要一次性手眼标定（证据等级 B，需 G0）。

### 2.4 官方 WLA：能直接用，但别把它当“指代正确”

- **A｜模型与训练。** WLA 6B，约 2500h，64 任务（桌面 + 全身；上一轮提到的“54 桌面 + 10 全身”未在本轮逐项复核），30 步 chunk，30fps，4 步扩散，54D 相对 EE 动作，60D state，图像用 head left + 左右腕，`image_size [336,448]`；action head 可在 24GB GPU 上微调；LoRA 可选（<https://github.com/unitreerobotics/unifolm-wla>，检索 2026-10-29）。
- **A｜配置。** `unitree.yaml` 里 `chunk_size=30`、`target_fps=30`；WLA server 的 `--instruction` 是固定 prompt，需要把挑战赛的 `language` 映射进去。
- **A｜改写采样。** dataloader 随机抽 5 条之一（第 515 行）；这既提供了语言多样性，也意味着**同一个场景在不同 epoch 会被不同改写监督**。如果模型只学会“关键词匹配”，它仍然会在测试时遇到没见过的改写/重复实例/干扰物时指错。
- **B｜能直接打榜首吗？** 不能。WLA 是官方基座，不是挑战赛专用 checkpoint；需要动作空间适配、相机名映射、语言映射、chunk 适配。它能在 24GB 上微调，这是我们的“单模型”底座。

### 2.5 头部模型路线的共同瓶颈

| 模型 | 公开路线要点 | 对“指代身份”的处理 | 对“受扰恢复”的处理 |
|---|---|---|---|
| MolmoAct2 | 动作推理 + 3D/depth 表征 + 双臂 | 依赖 VLM 的视觉指代；无显式身份后验 | 主要靠 replan；无重锚定状态机 |
| WALL-OSS-0.5 | 4B VLA（3B VLM + action expert） | 语言-视觉对齐；无负锚点 | progress ≠ success；无显式恢复 |
| DreamZero | 14B Wan2.1 world-action | 世界模型预测；身份靠隐空间 | 重；chunk 长；不适合低延迟恢复 |
| Spirit-v1.5 | VLA 路线 | 公开细节少；大概率表面匹配 | 未公开 |
| DM0 | VLA 路线 | 公开细节少 | 未公开 |
| π0.5 | 开放世界 VLA | 语言泛化好，但 LIBERO-Para/Rephrase 证明仍脆弱 | replan，无身份保持 |
| GigaBrain-0 | 世界模型数据 + VLA | 数据效率/物理保真 | 未公开 |
| GR00T N1.5 | 通用人形 VLA | 任务级 grounding | 任务专用精度/恢复弱 |

**共同点：** 都是“大 VLA + 开环 chunk + 语言表面匹配”；没有一家在 API 约束下显式维护“目标/容器/参考系”的身份后验，也没有一家把“人移动物体后重新绑定”做成确定性状态机。**这正是 REFER-SERVO 的空白。**

### 2.6 近期工作：四个证据链

1. **改写脆弱性。** LIBERO-Para 在 7 个 VLA 上做同义改写，平均掉 22–52pp；80–96% 的失败是 planning-level task identification，而不是底层控制（<https://arxiv.org/abs/2603.28301>，检索 2026-10-29）。Rephrase Before You Act 用 LLM 在测试时重写指令，相对提升 16–27%，但需要第二个 LLM（<https://arxiv.org/abs/2610.10526>）。**结论：语言表面匹配是真实瓶颈；但不要为此引入第二个在线大模型。**
2. **身份保持 grounding。** RefGuard 维护 target/anchor/frame 的联合后验，在歧义压力试次上零 identity switch、90.0% 正确执行，并在 post-grounding 场景变化后恢复 86.7%；其基线在 33–46% 的试次发生 identity switch。但它用 RGB-D（<https://arxiv.org/abs/2609.06221>）。GSR 把任务语义重新绑定到视觉特征，最高 +44.6pp，但需要架构改动（<https://arxiv.org/abs/2608.02497>）。**结论：身份后验有效；我们可以用 RGB 双目 + 腕部彩色替代 RGB-D，不引入第二个模型。**
3. **干扰物与遮挡。** DRAGON-VLA（又名 OBEYED-VLA）在 7 个干扰物下约 80%，基线 <10%；object-centric + depth grounding（<https://arxiv.org/abs/2512.22519>、<https://papers.ssrn.com/sol3/papers.cfm?abstract_id=7571503>，检索 2026-10-29）。EATR-Stereo 在严重非对称遮挡下恢复 80% vs 30%，但需要 stereo token routing/训练改动；A-FAR 提供主动视觉遮挡恢复基准与“动一下再看”的证据（<https://arxiv.org/abs/2609.37292>、<https://arxiv.org/abs/2608.17453>）。**结论：干扰物不是“多加数据”就能解决；需要显式负锚点和重观察。**
4. **人的社会干扰。** SocialVLA 在 G1 上识别语音/表情并 gate-to-hold，336ms；召回 54.6%/精确 69.5%（<https://arxiv.org/abs/2610.02360>）。**结论：人的干扰是“语义事件”，不只是视觉遮挡；但本赛题没有音频，我们只能用视觉 + 物体运动残差来检测。**

其他相关：TAG 用反事实物体擦除做 training-free 注意力引导（<https://arxiv.org/abs/2603.24584>）；CGVD 用指令解析 + 分割 + 修复做视觉退化鲁棒（<https://arxiv.org/abs/2603.10340>）；WM-VS 用进度对齐世界模型 + DINOv2 做视觉伺服（<https://arxiv.org/abs/2609.20892>）；ActGaze 用反事实 gaze 监督（<https://arxiv.org/abs/2609.28955>）；AnchorVLA4D 用 anchor image + 空间编码器（<https://arxiv.org/abs/2603.12730>）；TaskAnchor 用 task-state adapter（<https://arxiv.org/abs/2609.23580>）；MINT 用 missing-input 训练 + 预测做相机中断鲁棒（<https://arxiv.org/abs/2609.35003>）；FLARE 用 retry/reset + perturbation bridging + 在线 MLLM（<https://arxiv.org/abs/2608.26645>）；AR-WAM 用视觉 grounding prompt + operation token，0.5B/14.1ms（<https://arxiv.org/abs/2609.23578>）；CAP 用 contact anchor 替代语言（<https://arxiv.org/abs/2602.09017>）。

### 2.7 语音交互的真相：不是音频，是“指代”

- **A｜API 没有音频。** 没有麦克风通道，也没有 `audio` 字段；评测器不会“说话”。在线 ASR/TTS 不可能影响评分，只会增加延迟和合规风险。
- **A｜语言是固定文本。** `language` 在一个 episode 内不变；它不是对话，不是多轮指令，不是语音。
- **A｜数据有 5 条改写。** 这是“语音多样性”的文本代理；官方训练随机抽一条。**真正的可迁移工作是：让策略对“同一指代的不同说法”不变，而不是让策略“听懂语音”。**
- **C｜Unitree UnifoLM-OminiA-0.3 的语音交互是另一个产品/演示。** 它展示了语音 + 抗扰动的全身操作，但不是 UniBot-V1 挑战赛 API；不能把它的能力当成赛题通道。
- **C｜同一赛事的 Multimodal HRI 赛道。** 如果同一赛事/周边活动有 Multimodal HRI 赛道，真正的语音交互应该去那里或做演示，不要把它塞进 UniBot-V1 的单模型评分路径。
- **结论：** 本轮的“语音交互”= **离线同义改写/ASR/TTS 压力测试 + 指代锚定**；不是在线语音助手。

## 3. 诊断：最后 3 厘米之前，还有“前 3 个词”和“时间身份”

### 3.1 成功链与四类失败

```text
语言 l
  → 指代绑定 (target i, receptacle j, frame f)
  → 抓取/搬运 (VLA 30-step chunk)
  → 对齐/接触 (ARS 5-step servo)
  → 受扰恢复 (RAR re-anchor)
  → 成功
```

四类失败：
1. **身份切换（identity switch）**：把“红色积木”绑到橙色积木；把“左边杯子”绑到右边；把“带盖盒子”绑到另一个盒子；在多物体排序任务里把顺序/颜色绑错。LIBERO-Para 的 80–96% planning-level 失败、RefGuard 报告的基线 33–46% identity switch 都指向它。
2. **时间漂移（temporal drift）**：目标一开始对，但人把它挪走/遮挡/换背景后，策略继续执行旧 plan；或者夹爪靠近时目标被机械臂自身遮挡，跟踪器丢了却不自知。A-FAR/EATR-Stereo/MINT 都指向它。
3. **接触误差（contact miss）**：目标对了，但最后 3 厘米插入/拧/拉/倒/叠不准；开环 chunk 的累积误差 + RTT。第 12 轮 CHUNK-SERVO 的主战场。
4. **恢复失败（recovery fail）**：检测到异常但不会“停下来重新看”，或者重新看时又被干扰物带偏；SocialVLA 的 gate-to-hold 说明“停”本身是有价值的动作。

### 3.2 为什么 CHUNK-SERVO 不够

CHUNK-SERVO 的隐含假设是“目标已知”：它从 VLA 的 plan 里拿目标位姿，然后每 5 步做视觉伺服。这个假设在 32 个任务里经常不成立：
- 多物体任务（FruitSorting、ColorArrangement、OrganizeTools、PickOutBatteries、StackBowls、ArrangePlates、SpellRobot）需要“颜色/顺序/字母”级别的指代，不是“一个目标”。
- 容器任务（StoreEarphones、PackPhone、ToolboxStorage、OrganizeStationery、OrganizePencilCase）需要“目标 + 容器 + 插入轴”三个锚点，不是一个。
- 人的干扰（5 类泛化之一）会改变目标身份/位置；CHUNK-SERVO 会“精确地伺服到旧目标”。
- 同义改写（5 条）可能把“plug”说成“insert”“connect”“put into”；如果 VLA 只做关键词匹配，plan 会在第一步就偏。

**一句话：CHUNK-SERVO 解决“手抖”，REFER-SERVO 解决“眼瞎/认错/跟丢”。两者是乘法关系，不是替代关系。**

### 3.3 为什么现在能做

- **数据足够。** 32×5 条改写、33k 成功演示、每任务 969–1,533 episodes；可以离线构建锚图、检索 keyframe、做反事实增强。
- **标定足够。** 头部双目已校正（基线 58.2526mm）；腕部彩色有内参；EE 位姿可读；只缺腕部-EE 外参和头相机在线位姿，均可一次性标定/拟合。
- **基座足够。** WLA 6B 官方开源，24GB 可微调 action head；我们不需要从零训 VLA。
- **规则允许。** 单模型约束下，符号锚图、经典跟踪、确定性伺服、状态机都不是“第二个学习模型”；只要不引入第二个在线大模型，就不违反单模型。
- **评测允许试错。** 单任务不计分通道 + 320 trials 的正式赛；可以先用单任务通道做 A/B，再决定是否全量提交。

### 4.1 RAG：语言指代锚图（Referent Anchor Graph）

**做什么。** 离线把 32 个任务 × 5 条改写变成一张 JSON 图：每个任务有 canonical 指令、target 锚点、receptacle 锚点、relation、frame、affordance、negative anchors、subgoals、demo keyframes。在线只做字符串归一化 + 规则匹配 + 图查询，**不调用 LLM**。

**为什么不是“又一个 LLM”。** 5 条改写是已知的、有限的、可人工审阅的；用符号图比在线 LLM 更稳、更便宜、更合规。LLM 只在离线做辅助解析，产物是人工审阅过的 JSON。

**输出。** 在线得到 `AnchorSet`：
```json
{
  "task_id": "T26",
  "canonical": "Plug the Ethernet cable into the network port.",
  "target": {"class": "ethernet_cable", "attrs": ["black", "rj45"], "count": 1},
  "receptacle": {"class": "network_port", "attrs": ["black", "rectangular"], "count": 1},
  "relation": "insert",
  "frame": "base",
  "affordance": {"target": "plug_tip", "receptacle": "port_opening", "axis": "insertion_axis"},
  "negative_anchors": ["other_cables", "other_ports", "background"],
  "subgoals": ["grasp_plug", "align_axis", "insert", "release"],
  "keyframes": [{"episode": 12, "frame": 340, "T_target_ee": [0.0, 0.0, 0.02, 0.0, 0.0, 0.0]}]
}
```

**关键点。**
- `canonical` 用于 WLA 的 instruction；5 条改写用于离线压力测试。
- `negative_anchors` 是“不要抓/不要放”的显式负例；这比“多给正样本”更能抗干扰。
- `keyframes` 是“目标-夹爪相对位姿”的演示检索；第 12 轮已经证明这比绝对坐标稳。
- `frame` 明确是 base / target / receptacle / wrist；所有伺服误差都在同一帧里算，避免“base 系目标 + 腕部系误差”的混用。

### 4.2 IPAT：身份保持锚点跟踪（Identity-Preserving Anchor Tracker）

**做什么。** 用头部双目 + 腕部彩色，维护 `(target i, receptacle j, frame f)` 的联合后验；在“提交动作”之前延迟承诺；在置信度下降时主动重观察；用负锚点排除干扰物。

**候选生成。**
- 头部左目 + 右目：SGBM/块匹配得到视差 → 深度 → 桌面平面 → 连通域/颜色/形状候选。
- 腕部彩色：近距离 2D 候选 + 已知物体尺寸/关键点；用腕部内参反投影到 3D（深度来自头部双目或已知高度）。
- VLA 的 cross-attention/heatmap（如果可导出）：作为候选的弱先验，不单独决策。
- 演示 keyframe 的 appearance embedding（离线，CPU/GPU 均可）：作为重识别特征。

**联合后验（规则化，不训练）：**
```text
p(i, j, f | I, l) ∝ p(l | i, j, f) · p(I | i, j, f) · p(i, j, f)
```
- `p(l | i, j, f)`：属性/关系匹配（颜色、形状、左右、大小、容器/工具关系）；由 RAG 的规则给出。
- `p(I | i, j, f)`：跟踪器/深度/重识别的外观与几何一致性。
- `p(i, j, f)`：任务锚图 + 桌面几何先验（目标通常在容器左侧/上方等）。
- **不做端到端学习**；所有项都是可解释的分数，便于调试和消融。

**延迟承诺（delay commitment）。** 不在第一帧就锁死目标；在 `K` 帧（建议 3–5 帧）内维护 top-2 假设，等夹爪靠近/遮挡减少后再提交。这样可以用少量等待换取身份正确率。RefGuard 的“联合后验 + 场景变化恢复”是同一思路的 RGB-D 版本；我们用双目 + 腕部彩色替代。

**主动重观察（active re-observation）。** 当 `max p < τ_id` 或 top-2 差距 < `τ_margin` 时，执行一个小的“观察动作”：抬腕/侧移/回到 keyframe 视角，重新观测 200–400ms，再更新后验。这个动作要计入 180s 预算，只在必要时触发。

**负锚点。** 对每个任务显式列出“相似但错误”的实例（其他颜色积木、其他杯子、其他线缆、背景纹理）；后验里对负锚点做减法，而不是只对正锚点做加法。

### 4.3 ARS：锚相对 5 步视觉伺服（Anchor-Relative Servo）

**做什么。** 在 VLA 的 30 步 plan 内，每 5 步用当前图像 + 锚点后验，重算“目标相对夹爪”的位姿，输出一个短闭环修正；chunk 内仍按 API 开环执行，但每 5 步重置一次误差。

**与 CHUNK-SERVO 的区别。** CHUNK-SERVO 用“目标绝对位姿 + 演示相对位姿”；ARS 用“锚点后验 + 目标/容器/插入轴”：
- 对插入任务，误差不是“目标中心到夹爪”，而是“插头尖端到端口开口 + 插入轴对齐”。
- 对堆叠/排序任务，误差是“目标槽位/颜色位置”，不是“物体中心”。
- 对容器任务，误差是“目标到容器口 + 容器轴”，不是“目标到桌面”。
- 对受扰任务，锚点后验会先更新，再伺服；不会“精确地追旧目标”。

**控制律（与第 12 轮一致，只换锚点）：**
```text
e = log(T_ee^{-1} · T_target · T_target_ee*)
Δ = clip(Kp · e + Kd · ė, ±δ)
```
- `T_target` 来自 IPAT 的后验均值/众数；`T_target_ee*` 来自演示 keyframe 检索。
- 平移增益 `Kp` 建议 0.3–0.6，旋转 0.2–0.4；`δ` 按任务限幅（插入 2–5mm/步，堆叠 5–10mm/步）。
- 腕部彩色做 2D IBVS 精调：用腕部内参把 3D 误差投到图像，直接压像素误差；头部双目做 PBVS 粗调。
- 接触段（最后 5–10mm）降增益、加死区、限速度；不假装有力传感器。

**延迟补偿。** 用 `send_time`/`receive_time` 估计 RTT；用恒定速度模型预测 `T_target(t+τ)`；RTT 抖动大时退回“小步 + 高阻尼”，不做大 jump。

### 4.4 RAR：重锚定恢复（Re-Anchoring Recovery）

**做什么。** 检测“世界变了”，停下来，重新看，重新绑定，再继续。它不是一个新模型，而是一个状态机 + 残差检测器。

**检测信号。**
- 目标残差：`r_a(t) = || T_target(t) - T_target^pred(t) ||`，其中 `T_target^pred` 由上一帧锚点 + 机器人自身运动预测（假设物体静止）。`r_a > θ_m` 连续 `K` 帧 → 外部编辑。
- 遮挡/丢失：跟踪置信度 `< τ_track`，或目标像素面积骤降 > 50%。
- 抓取后：如果物体已被夹住，目标应随 EE 运动；用 `r_grasp = || T_target(t) - T_ee(t) · T_ee_target* ||` 判断“掉了/被拿走”。
- 人的干扰：画面中出现快速移动的大连通域/手部肤色区域，且目标残差同时升高 → 优先触发 RAR，而不是继续伺服。

**状态机。**
```text
SERVO ──(r_a > θ_m, K 帧)──▶ HOLD
HOLD ──(200ms 稳定)──▶ REOBSERVE
REOBSERVE ──(找到 top-1, p > τ_id)──▶ REANCHOR
REANCHOR ──(更新 T_target/T_receptacle)──▶ SERVO
REOBSERVE ──(超时/找不到)──▶ VLA_REPLAN
VLA_REPLAN ──(新 plan)──▶ SERVO
```
- HOLD 期间输出零速度/保持位姿；这是“安全”的动作，不是浪费时间。
- REOBSERVE 优先回到 keyframe 视角/抬腕；用负锚点排除干扰物。
- 如果目标被移到桌面外/不可达，直接 VLA_REPLAN，不要硬追。
- 所有状态转换打日志；用单任务通道做离线回放。

### 4.5 PRT：同义改写/反事实干扰训练（Paraphrase-Robust Training，可选）

**做什么。** 如果 WLA 的 zero-shot 指代不够稳，做离线增强 + action head 微调；不引入第二个在线模型。

- **改写增强**：每条任务 5 条官方改写 + TTS/ASR 回译变体（离线生成，人工抽检）；训练时随机抽一条（官方已经在做），并额外做“关键词遮挡/替换”压力测试。
- **锚点裁剪**：把 target/receptacle 区域裁剪成额外视图/ token，强制模型看“物体”而不是“背景”。可用离线分割/检测生成伪标签，不在线跑大模型。
- **反事实干扰**：把相似物体复制/粘贴到背景/目标附近，标签仍是原目标；训练模型忽略负锚点。参考 TAG 的反事实擦除、DRAGON 的 object-centric 思路。
- **ActGaze 式监督**：如果能有 gaze/attention 伪标签，监督“看目标/容器/接触点”；没有就跳过，不硬造。
- **训练配置**：WLA action head，24GB，LoRA 可选；冻结 VLM，只训 action head/适配层；数据按 session/物体/背景分组划分，避免泄漏。

**注意。** PRT 是“可选加分项”，不是“必须项”。如果 G2/G5 已经过，不要为了 PRT 引入训练风险；先把 RAG/IPAT/ARS/RAR 的工程闭环跑通。

### 4.6 合规性：为什么这不是“第二个模型”

| 组件 | 是否学习模型 | 在线是否新增权重 | 合规判断 |
|---|---|---|---|
| RAG | 否，符号 JSON + 规则 | 否 | 合规 |
| IPAT | 经典 CV + 规则后验 | 否 | 合规 |
| ARS | 确定性控制 | 否 | 合规 |
| RAR | 状态机 + 残差 | 否 | 合规 |

**红线：** 不运行第二个在线 VLA/LLM/分割大模型；不把多个 checkpoint 集成；不把评测器的 token/隐藏状态拿来做额外模型。所有在线学习能力都来自 WLA 本身。

## 5. 创新点清单（动机 / 差异 / 可行性 / 资源 / 步骤 / 风险）

> 这是本轮要维护的“持续迭代清单”。第 12 轮的 CHUNK-SERVO 是 C（ARS）的前身；本轮新增 A（RAG）、B（IPAT）、D（RAR），E（PRT）是可选训练增强。本节引用的外部数字见 §2.6 与产物区来源表；检索日期均为 **2026-10-29**。

### 5.1 创新点 A：RAG——语言指代锚图（把“语音”变成“指代”）

- **动机。** 5 条同义改写 + 重复实例 + 干扰物 + 未见物体；LIBERO-Para 掉 22–52pp，80–96% 失败在 planning-level task identification。
- **与现有方案的差异。** 不是在线 LLM 重写（Rephrase Before You Act），不是第二个 VLM（DRAGON/CGVD），而是**离线、有限、可审计的 32×5 锚图**；在线只做字符串归一化 + 图查询。它把“语言理解”降级为“指代检索”，把不可控的生成变成可控的查表。
- **技术可行性。** 32 个任务、5 条改写，人工/半自动解析 1–2 人周；JSON schema 固定；CPU 查询 <1ms；不需要 GPU。
- **所需资源。** 数据集 `tasks.parquet`、挑战页任务说明、演示 keyframes；1 名工程师 + 1 名标注；无需额外算力。
- **落地步骤。** ① 抽取 32×5 文本；② 人工标注 target/receptacle/relation/frame/negative anchors；③ 生成 JSON + JSON Schema 校验；④ 写 canonicalizer（归一化、同义词、左右/颜色/顺序解析）；⑤ 单元测试：32×5 全部命中同一锚图；⑥ 离线用 WLA 的 instruction 做一致性检查。
- **风险。** 解析错误/歧义（如“left”是图像左还是物体左）；重复实例无法只靠文本区分；未见物体没有锚点。**缓解：** 歧义时保留 top-2 假设交给 IPAT；未见物体回退到 VLA 的开放词汇 grounding；所有解析错误可人工修正。
- **成功指标。** 32×5 锚图一致率 ≥95%；canonicalizer 在 5 条改写上的准确率 ≥98%；离线指代错误率相对 baseline 降 ≥30%。

### 5.2 创新点 B：IPAT——身份保持锚点跟踪（抗干扰的核心）

- **动机。** 干扰物、背景变化、遮挡、人移动物体；现有 VLA 没有显式身份后验，容易“抓错/跟丢/追旧目标”。
- **与现有方案的差异。** RefGuard 用 RGB-D + 联合后验；我们用**头部双目 + 腕部彩色 + 规则后验**，不引入第二个学习模型。DRAGON 用 object-centric + depth；我们用负锚点 + 延迟承诺 + 主动重观察，成本更低。A-FAR/EATR-Stereo 需要训练/架构改动；我们是 inference-time 层。
- **技术可行性。** 头部双目已校正；腕部彩色有内参；SGBM/颜色/形状/重识别都是成熟 CV；CPU 10–30ms/帧；后验是规则化的，可解释、可调。
- **所需资源。** 双目标定、腕部内参、腕部-EE 外参（一次性手眼标定）、演示 keyframes；CPU；1 名 CV 工程师 3–4 周。
- **落地步骤。** ① 候选生成（双目深度 + 桌面平面 + 颜色/形状）；② 后验打分（语言属性 + 外观 + 几何 + 负锚点）；③ 跟踪（KCF/CSRT/光流/重识别，按场景选）；④ 延迟承诺（top-2 保持 3–5 帧）；⑤ 主动重观察策略；⑥ 离线回放 + 单任务 A/B。
- **风险。** 透明/反光物体（玻璃杯、塑料包装）深度差；快速运动/遮挡导致跟踪丢失；腕部近距景深/运动模糊。**缓解：** 多模态分数（颜色/形状/深度/重识别）；丢失即触发 RAR；对透明物体用边缘/背景差分/已知尺寸，不迷信深度。
- **成功指标。** 离线 identity switch rate ≤5%（含干扰物/重复实例）；跟踪成功率 ≥80%；重识别 top-1 ≥85%；在线单任务 A/B 指代错误降 ≥50%。

### 5.3 创新点 C：ARS——锚相对 5 步视觉伺服（最后 3 厘米）

- **动机。** 开环 chunk 的累积误差 + RTT；插入/拧/拉/倒/叠的最后 3 厘米；第 12 轮已验证“5 步伺服”方向，但还缺“锚相对”。
- **与现有方案的差异。** CHUNK-SERVO 用绝对目标 + 演示相对位姿；ARS 用**目标/容器/插入轴**三个锚点，误差定义随任务变；腕部彩色内参用于 2D IBVS 精调；头部双目用于 PBVS 粗调；接触段降增益，不假装有力传感器。
- **技术可行性。** 第 12 轮已有 5 步伺服骨架；腕部内参已确认；头部双目可测深；控制律是经典 IBVS/PBVS；CPU <5ms/步；无需训练。
- **所需资源。** WLA plan、标定、单任务通道；CPU + 1 张 GPU（WLA）；1 名控制工程师 2–3 周。
- **落地步骤。** ① 动作适配（WLA 54D→API 21D）；② 锚点误差定义（按任务类型）；③ 增益/限幅/死区整定；④ 延迟补偿；⑤ 单任务 A/B：chunk=5 vs 30，servo on/off；⑥ 消融：IBVS vs PBVS vs 混合。
- **风险。** RTT 抖动导致振荡；标定误差；透明/反光物体 2D 误差不可靠；接触段过冲。**缓解：** 小步 + 高阻尼；RTT 大时退回开环；接触段力限/速度限；用单任务通道先验证。
- **成功指标。** 插入类横向 ≤2mm、深度 ≤3mm；2s 保持 ≥95%；RTT 0–150ms 稳定；单任务 +10pp（A/B 类 4 个中 ≥3 个）。

### 5.4 创新点 D：RAR——重锚定恢复（人为干扰轴）

- **动机。** 5 类泛化里的“人为干扰”占 20% trials；人会把物体挪走/遮挡/换位置；现有 VLA 只会 replan，不会“停下来重新看”。
- **与现有方案的差异。** FLARE 用 retry/reset + 在线 MLLM 监控；我们用**残差检测 + 状态机 + 主动重观察 + 负锚点**，不引入第二个模型。SocialVLA 用语音/表情 gate-to-hold；我们没有音频，用视觉 + 物体运动残差。MINT 用 missing-input 训练；我们是 inference-time 恢复。
- **技术可行性。** 残差/置信度/像素面积都是轻量信号；状态机简单；200ms 检测目标可达；不需要训练。
- **所需资源。** 头部双目/腕部彩色、EE 位姿、单任务通道；CPU；1 名工程师 2–3 周。
- **落地步骤。** ① 定义残差（目标/抓取后/遮挡）；② 阈值整定（离线回放 + 单任务）；③ 状态机（HOLD/REOBSERVE/REANCHOR/REPLAN）；④ 重观察动作库（抬腕/侧移/回 keyframe）；⑤ 与 ARS 的切换；⑥ A/B：RAR on/off，人为干扰子集。
- **风险。** 目标被移到视野外/桌面外；误触发导致时间浪费；重观察时又被干扰物带偏。**缓解：** 超时即 VLA_REPLAN；误触发率 ≤5%；负锚点 + top-2 后验；180s 预算内限制重观察次数（建议 ≤3 次/任务）。
- **成功指标。** 干扰检测 ≤200ms；重锚定成功率 ≥70%；误触发率 ≤5%；人为干扰子集 +10pp。

### 5.5 创新点 E：PRT——同义改写/反事实干扰训练（可选）

- **动机。** 如果 zero-shot 指代不够稳，WLA 仍会表面匹配；官方已随机抽 5 条改写，但没显式教“忽略干扰物/看锚点”。
- **与现有方案的差异。** 不是第二个模型；是在 WLA 同一 checkpoint 上做离线增强 + action head 微调；强调 anchor crop + counterfactual distractors + 负锚点，而不是堆数据。
- **技术可行性。** WLA action head 24GB 可微调；LoRA 可选；33k demos 足够；增强是图像/文本级，不需要新标注（可用离线检测/分割生成伪标签）。
- **所需资源。** 1×24GB GPU；1–2 GPU-weeks；1 名训练工程师；数据管线。
- **落地步骤。** ① 改写/TTS/ASR 变体；② anchor crop/伪标签；③ 反事实干扰合成；④ 分组划分；⑤ 微调 + 消融；⑥ 只在 G2/G5 未过时启用。
- **风险。** 合成干扰不真实；过拟合；算力/时间不够；可能破坏原有泛化。**缓解：** 小学习率/LoRA；只在 action head；保留原 checkpoint 做回退；离线/单任务先验证。
- **成功指标。** 改写子集 +5–10pp；干扰物子集 +5–10pp；其他任务不回归 >3pp。

- W1：W0 + RAG + IPAT。

- W3：W2 + RAR。
- W4：W3 + PRT（可选）。

### 7.4 算术：别把 +10pp 乘 32

正式赛 32 任务 × 10 trials = 320 trials。单任务 10 trials 的成功率粒度是 10pp，标准误约 `sqrt(p(1-p)/10)`；p=0.5 时 SE≈15.8pp，所以**单任务 10 trials 的噪声很大**。全赛 320 trials 的 SE≈`sqrt(0.5×0.5/320)`≈2.8pp（p=0.5），配对设计可降低方差。

保守估算：
- 12 个 A 任务 +8pp → `12/32 × 8 = +3.0pp`
- 12 个 B 任务 +8pp → `12/32 × 8 = +3.0pp`
- 合计 +6pp（如果 A/B 都过）
- 若只有 8 个任务过 +8pp → +2pp
- 若 24 个任务 +5pp → +3.75pp

**结论：REFER-SERVO 的目标不是“每个任务 +30pp”，而是“在 12–24 个任务上稳定 +5–10pp”，全局 +3–7pp。** 对榜首 29.7% 的预览基线，这足以改变名次；对真实基线未知的情况，这是稳健的工程增量。

| G1 RAG | 32×5 是否绑定到同一锚图 | 一致率 ≥95%；canonicalizer ≥98% | 人工修正；歧义保留 top-2 |
| G2 IPAT | 干扰物/重复实例下是否抓对 | identity switch ≤5%；跟踪 ≥80%；重识别 top-1 ≥85% | 加负锚点/延迟承诺；回退 VLA |
| G3 ARS | 最后 3 厘米是否稳 | 横向 ≤2mm、深度 ≤3mm；2s 保持 ≥95%；RTT 0–150ms 稳定 | 降增益/加死区；改 PBVS/IBVS |
| G4 RAR | 人移动/遮挡后是否恢复 | 检测 ≤200ms；重锚定 ≥70%；误触发 ≤5% | 调阈值；限制重观察次数 |
| G5 单任务 | 是否真的涨分 | A/B 类 4 个中 ≥3 个 +10pp；FoldTowel 不回归 >5pp | 缩范围；只保留有效模块 |
| G6 延迟 | 是否超时/抖动 | 伺服 p99 ≤150ms；VLA 查询预算内；无 180s 超时 | 降频/缓存/异步 |
| G7 全量 dry run | N 端口是否稳定 | 无崩溃/内存泄漏/串扰；reset 干净 | 修并发/资源 |
| G8 消融 | 每个模块是否必要 | RAG/IPAT/ARS/RAR 各自 on/off 有可解释差异 | 剪掉无效模块 |
| G9 榜单监控 | 预览数据是否变化 | JSON/页面一致；不逐任务过拟合 | 只当参考 |

**Gate 纪律：** 任何模块未过 G0–G4，不进入正式提交；任何模块在 G5 没有 +10pp 方向性收益，不进入全量；任何模块让 C 类回归 >5pp，回退。

## 9. 风险与合规

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 单模型违规（第二个在线模型） | 中 | 高 | RAG/IPAT/ARS/RAR 全符号/经典/确定性；PRT 只微调同一 WLA |
| 指代后验错误 | 中 | 高 | top-2 延迟承诺；负锚点；回退 VLA |
| 跟踪漂移/遮挡 | 高 | 中 | 置信度阈值；RAR；重识别 |
| 透明/反光物体 | 高 | 中 | 边缘/颜色/已知尺寸；不迷信深度 |
| RTT 抖动 | 中 | 中 | 小步/高阻尼；RTT 大时开环 |
| 标定误差 | 中 | 中 | G0；每机器人重标；已知尺寸校验 |
| 重观察耗时 | 中 | 中 | ≤3 次/任务；200–400ms/次；超时 replan |
| 人为干扰误触发 | 中 | 中 | 残差 + 面积 + 置信度联合；误触发 ≤5% |
| 数据泄漏 | 中 | 高 | 按 session/物体/背景分组；相邻帧不跨 split |
| 评测噪声 | 高 | 中 | 配对 A/B；bootstrap；320 trials |
| 预览榜单误导 | 高 | 中 | 只当难度信号；不逐任务过拟合 |
| 语音演示越界 | 低 | 中 | 离线/演示不进入评分；不混赛道 |

**合规红线：**
- 不运行第二个在线 VLA/LLM/分割大模型；不集成多 checkpoint。
- 不修改评测器/令牌/隐藏状态；不绕过 API。
- 不把语音/ASR/TTS 放进评分路径（无音频，且可能被视为额外模型）。
- 所有外部数据/模型遵守许可证；不泄露 API token。
- 安全：HOLD/限速/限幅；人干扰时优先停机，不硬追。

## 10. 一句话押注

**当前最值得押注：REFER-SERVO——用 32×5 条指令构建语言指代锚图，用头部双目 + 腕部彩色维护目标/容器/参考系的身份后验，用 5 步锚相对视觉伺服补最后 3 厘米，用重锚定状态机抗人为干扰；语音只做离线同义改写压力测试，不做在线 ASR/TTS。**

## 2. 形式化

### 2.1 成功链

近似分解（不是严格独立，但便于分诊）：

```text
P(success | l, I, robot) ≈
  P(i, j, f | l, I)          # 指代身份
  × P(grasp | i, f)          # 抓取
  × P(transport | i, j, f)   # 搬运
  × P(contact | i, j, f)     # 对齐/接触
  × P(recover | disturbance) # 受扰恢复
```

其中 `i` 是目标实例，`j` 是容器/锚点实例，`f` 是参考系（base/target/receptacle/wrist）。

**关键不等式：**

```text
P(success) ≤ min(P(identity), P(grasp), P(transport), P(contact), P(recover))
```

所以“把接触做到 99% 但身份只有 70%”仍然是 70% 上限。REFER-SERVO 先补最低的那一项。

### 2.2 身份后验

```text
p(i, j, f | I, l) ∝ p(l | i, j, f) · p(I | i, j, f) · p(i, j, f)
```

- `p(l | i, j, f)`：语言属性/关系匹配（颜色、形状、左右、大小、容器/工具关系、顺序）。
- `p(I | i, j, f)`：图像证据（外观、深度、几何、跟踪置信度、keyframe 相似度）。
- `p(i, j, f)`：任务锚图 + 桌面几何先验（目标通常在容器左侧/上方等）。

**规则化打分（在线不训练）：**

```text
S(i, j, f) =
    w_l · S_lang(i, j, f | l)
  + w_a · S_app(i | I)
  + w_g · S_geom(i, j, f | I)
  + w_k · S_key(i, j | keyframes)
  - w_n · S_neg(i, j | negative_anchors)

p(i, j, f) = softmax(S / T)
```

建议初始权重：`w_l=1.0, w_a=0.8, w_g=0.6, w_k=0.5, w_n=1.2`；`T=0.2`。这些是起点，按 G2 调。

**延迟承诺：**

```text
keep top-2 hypotheses for K frames (K=3..5)
commit when:
  p_top1 > τ_id (0.65) and (p_top1 - p_top2) > τ_margin (0.15)
  or distance(gripper, target) < 0.15 m
else:
  active re-observe (small motion) or fallback to VLA
```

**为什么延迟承诺有效：** 第一帧往往被遮挡/歧义；等夹爪靠近、视角变化、遮挡减少后再锁定，可以用少量等待换身份正确率。RefGuard 的联合后验是同一思路的 RGB-D 版本；我们用头部双目 + 腕部彩色替代。

### 2.3 锚相对伺服误差

定义：
- `T_ee`：当前 EE 在 base 系的位姿。
- `T_target`：目标在 base 系的位姿（来自 IPAT 后验）。
- `T_target_ee*`：演示检索得到的“目标系下的期望 EE 位姿”。
- `T_receptacle`：容器/槽位在 base 系的位姿。
- `T_receptacle_ee*`：演示检索得到的“容器系下的期望 EE 位姿”。

**自由空间（PBVS）：**

```text
e = log( T_ee^{-1} · T_target · T_target_ee* )
Δ = clip(Kp · e + Kd · ė, ±δ)
```

**插入/接触（锚相对）：**

```text
z_t = target 的插入轴（target 系）
z_r = receptacle 的插入轴（receptacle 系）
e_axis = z_t × z_r                    # 轴对齐误差
e_lat  = project( T_receptacle^{-1} T_target · p_tip - p_port, plane ⊥ z_r )
e_depth = dot( p_tip - p_port, z_r )  # 插入深度
```

控制：
```text
Δ_lat   = clip(K_lat · e_lat, ±2 mm/step)
Δ_axis  = clip(K_axis · e_axis, ±0.02 rad/step)
Δ_depth = clip(K_depth · e_depth, ±3 mm/step)
```

**腕部 2D IBVS 精调：**

```text
e_2d = s_current - s_desired
Δ = -λ · L^+ · e_2d
```

其中 `L` 是交互矩阵；对 2D 点特征，`L = [[-f/Z, 0, u/Z, uv/f, -(f+u^2/f), v], [0, -f/Z, v/Z, f+v^2/f, -uv/f, -u]]`。在线只用平移/小旋转，`L` 可近似为常数。

**为什么用腕部彩色：** 腕部内参已知（fx≈436），在 0.2–0.3m 工作距离上 1px≈0.46–0.69mm；这比头部双目在 0.5–1.0m 的分辨率更高。深度用头部双目/已知尺寸补，不用腕部 IR。

### 2.4 延迟与稳定性

RTT 估计：
```text
τ = (t_recv - t_send)/2 + t_server
```
（如果只有总 RTT，用 `τ ≈ RTT/2`；保守取 `RTT`。）

目标预测（恒速模型）：
```text
p_target(t+τ) ≈ p_target(t) + v_target · τ
T_target(t+τ) ≈ T_target(t) · exp(τ · ξ)
```
`ξ` 是物体旋量；静止物体 `ξ=0`。

稳定性约束（一阶近似）：
```text
Kp < 1 / (τ · f_ctrl)
```
其中 `f_ctrl` 是伺服频率。若 `τ=100ms`、`f_ctrl=30Hz`，`Kp < 0.33`；所以增益要小，宁可多步收敛。

**chunk 选择：**
- RTT < 50ms：chunk=3–5，`Kp=0.4–0.6`。
- 50–150ms：chunk=5，`Kp=0.25–0.4`。
- >150ms：chunk=8–10，`Kp=0.15–0.25`；或退回开环 + 稀疏修正。

### 2.5 评分与不确定度

正式赛 32×10=320 trials。成功率均值 `p` 的标准误：
```text
SE = sqrt(p(1-p)/320)
p=0.5 → SE≈2.8pp
p=0.3 → SE≈2.6pp
```

单任务 10 trials：
```text
SE = sqrt(p(1-p)/10)
p=0.5 → SE≈15.8pp
```

单任务 5 trials A/B：
```text
SE = sqrt(p(1-p)/5)
p=0.5 → SE≈22.4pp
```
**所以 5 trials 只能看方向，不能宣称显著；正式结论用 320 trials 配对 bootstrap。**

### 3.3 主循环伪代码

```python
def policy_loop(env):
    obs = env.reset()
    anchors = RAG.canonicalize(obs.language)
    ipat.reset(anchors)
    plan = wla.plan(obs, anchors.canonical)
    state = "SERVO"
    step = 0

    while not env.done and step < MAX_STEPS:
        # 1) 感知/身份
        ipat.update(obs, anchors)
        target = ipat.commit_or_top1()

        # 2) 受扰检测
        event = rar.detect(obs, target, ipat, last_cmd)
        if event:
            state = rar.transition(state, event)

        # 3) 规划/伺服
        if state == "SERVO":
            if step % PLAN_EVERY == 0:
                plan = wla.plan(obs, anchors.canonical)
            cmd = ars.step(obs, target, plan, anchors)
        elif state == "HOLD":
            cmd = hold_pose(obs)
        elif state == "REOBSERVE":
            cmd = reobserve_action(obs, anchors)
        elif state == "REANCHOR":
            ipat.reanchor(obs, anchors)
            state = "SERVO"
            cmd = hold_pose(obs)
        elif state == "REPLAN":
            plan = wla.plan(obs, anchors.canonical)
            state = "SERVO"
            cmd = hold_pose(obs)

        # 4) 执行
        obs = env.step(cmd)
        step += 1
```

**实际 chunk 语义：** `env.step(cmd)` 返回的是一个 chunk；上面的循环是逻辑步。ARS 每 5 步重算一次；WLA 每 30 步重规划一次；RAR 可在 chunk 边界打断（API 不允许 chunk 内打断）。

### 4.4 Canonicalizer：不训练的确定性映射

```python
def canonicalize(language: str, rag: dict) -> AnchorSet:
    s = normalize(language)  # lower, strip punctuation, collapse spaces
    # 1) exact/near-exact match to 5 paraphrases
    for task in rag.values():
        if s in {normalize(p) for p in task["paraphrases"]}:
            return task
    # 2) keyword/attribute rules
    hits = []
    for task in rag.values():
        score = keyword_score(s, task)
        hits.append((score, task))
    hits.sort(key=lambda x: -x[0])
    if hits[0][0] >= ACCEPT_THRESHOLD:
        return hits[0][1]
    # 3) fallback: VLA open-vocabulary grounding + log
    return FALLBACK_ANCHOR
```

**规则示例：**
- `plug|insert|connect|put into` → `insert`
- `hang|hook` → `hang`
- `sort|match|matching color` → `sort`
- `stack|pile` → `stack`
- `fold` → `fold`
- `zip|zipper` → `zip`
- `left|right` → 相对参考系（先按图像左/右，再用目标-容器关系消歧）
- `red|green|yellow|blue` → 颜色属性
- `first|then|order` → 顺序/子目标

**歧义处理：**
- 如果两个任务的 keyword score 接近（差 < 0.1），保留 top-2，交给 IPAT 的图像证据。
- 如果语言提到“左边/右边”，但图像中有多个同色实例，保留 top-2，延迟承诺。
- 如果语言包含未见物体/颜色，回退到 VLA 的开放词汇 grounding；RAG 只提供 relation/frame。

### 4.5 Keyframe 检索

**目标：** 从 33k 成功演示中检索“目标-夹爪相对位姿”，而不是绝对坐标。

**离线：**
- 对每个任务，按物体/容器/颜色/位置分桶；每桶保留 20–50 个 keyframe。
- 每个 keyframe 存：`episode`, `frame`, `T_target_ee`（目标系下 EE 位姿）, `T_receptacle_ee`（容器系下 EE 位姿）, 外观特征（颜色直方图/ORB/轻量 embedding）, 夹爪状态, 子目标标签。
- 用 `state_left_ee_pose`/`state_right_ee_pose` 和 `state_d435` 计算相对位姿；用 `recomputed_ee_valid` 过滤坏帧。

**在线：**
- 用 RAG 的 `task_id` + IPAT 的后验 `target/receptacle` 选桶。
- 用外观/几何相似度选 top-k keyframe；取中位数/加权平均，避免单个坏帧。
- 如果 top-k 分差大，保留多个候选，交给 ARS 的增益调度。

**为什么不用绝对坐标：** 绝对坐标对位置泛化（5 轴之一）不鲁棒；相对位姿把“目标在哪里”与“夹爪怎么对”解耦，换位置时仍可用。

## 5. IPAT：身份保持锚点跟踪

### 5.1 候选生成

**输入：** 头部左/右 RGB、腕部左/右 RGB、EE 位姿、语言锚图、桌面平面。

**步骤：**
1. **头部双目校正/匹配。** 用官方 `head_stereo` 的 R/T/畸变；SGBM 或块匹配；得到视差 `d`；`Z = f B / d`。
   - `f≈282.37 px`，`B=0.0582526 m`。
   - 0.5m：`d≈32.9 px`；1.0m：`d≈16.4 px`。
   - 深度噪声（0.1px 视差）：0.5m≈1.5mm；1.0m≈6.1mm。
2. **桌面平面。** 对深度图 RANSAC 拟合平面；物体 = 平面上方 5–30cm 的连通域。
3. **颜色/形状候选。** HSV/Lab 阈值 + 连通域 + 轮廓面积/圆度/长宽比/高度；按 RAG 的颜色/形状属性过滤。
4. **腕部候选。** 在腕部彩色图中用颜色/模板/关键点找目标；用腕部内参反投影到 3D（深度来自头部双目或已知桌面高度）。
5. **Keyframe 重识别。** 颜色直方图/ORB/轻量 embedding 与离线 keyframe 比对；只在 CPU 上做 top-k。
6. **VLA 注意力（可选）。** 如果 WLA 能导出 cross-attention/heatmap，作为弱先验；不单独决策。

**候选结构：**
```python
Candidate = {
  "id": int,
  "class": str,
  "bbox_head": (u1, v1, u2, v2),
  "bbox_wrist": (u1, v1, u2, v2) | None,
  "p3d": np.ndarray,       # base frame
  "R": np.ndarray,         # orientation (if available)
  "score": float,
  "source": "stereo|wrist|keyframe|vla",
}
```

### 5.2 后验打分

```python
def score_candidate(c, anchors, obs, keyframes):
    s_lang = attribute_match(c, anchors.target)       # 0..1
    s_app  = appearance_similarity(c, anchors, keyframes)  # 0..1
    s_geom = geometry_consistency(c, anchors, obs)    # 0..1
    s_key  = keyframe_similarity(c, keyframes)        # 0..1
    s_neg  = negative_penalty(c, anchors.negative_anchors)  # 0..1
    return 1.0*s_lang + 0.8*s_app + 0.6*s_geom + 0.5*s_key - 1.2*s_neg
```

**属性匹配：**
- 颜色：Lab 空间最近色；多峰颜色用直方图。
- 形状：面积/圆度/长宽比/高度；透明物体用边缘/背景差分。
- 左右：图像左/右 + 目标-容器关系；不要只按图像坐标。
- 顺序：从 RAG 的 `subgoals`/颜色序列得到期望顺序；已放置的实例从候选中移除。

**负锚点：**
- 其他颜色积木、其他杯子、其他线缆、其他端口、背景纹理。
- 对负锚点做减法；如果候选与负锚点相似度高，降权。
- 负锚点不是“黑名单”，而是“相似但错误”的显式建模。

### 5.3 跟踪

**短时跟踪：** CSRT/KCF/光流（Farneback/LK）；每帧更新 bbox；每 5–10 帧用检测重初始化。
**重识别：** 颜色直方图 + ORB + keyframe embedding；当跟踪置信度低/遮挡/目标被移动时触发。
**3D 跟踪：** 用头部双目深度更新 `p3d`；用 EE 位姿和桌面平面约束；用卡尔曼滤波平滑（恒定速度模型）。

**置信度：**
```text
conf = w1 * tracker_score + w2 * detector_score + w3 * keyframe_score - w4 * occlusion_score
```
- `conf < 0.3` 连续 3 帧 → RAR 的 `REOBSERVE`。
- 目标 bbox 面积骤降 >50% → 遮挡/移走。
- 目标 `p3d` 突变 >5mm/帧（静止物体）→ 外部编辑。

### 5.4 延迟承诺与主动重观察

**延迟承诺：**
```python
top2 = posterior.topk(2)
if top2[0].p > 0.65 and (top2[0].p - top2[1].p) > 0.15:
    commit(top2[0])
elif gripper_distance(top2[0]) < 0.15:
    commit(top2[0])  # 靠近时必须做决定
else:
    keep_top2()
```

**主动重观察：**
- 触发：`p_top1 < 0.65` 或 margin < 0.15 或 `conf < 0.3`。
- 动作库：腕部后撤 5–10cm；腕部侧移 5cm；头部/腰部微转；回到 keyframe 视角；等待 200–400ms。
- 选择：用 keyframe 的相机位姿作为目标视角；或用“最大化 top-2 分离度”的小动作（近似信息增益）。
- 预算：≤3 次/任务；每次 ≤400ms；总 ≤1.2s；超时 → VLA_REPLAN。
- 安全：动作在工作空间内；不碰撞；人在附近时先 HOLD。

### 5.5 伪代码

```python
class IPAT:
    def update(self, obs, anchors):
        cands = []
        cands += stereo_candidates(obs.head_left, obs.head_right, anchors)
        cands += wrist_candidates(obs.wrist_left, obs.wrist_right, anchors)
        cands += keyframe_candidates(obs, anchors)
        for c in cands:
            c.score = score_candidate(c, anchors, obs, self.keyframes)
        self.belief = softmax([c.score for c in cands])
        self.top2 = topk(cands, 2)

    def commit_or_top1(self):
        if self.committed:
            return self.committed
        if self.top2[0].p > 0.65 and margin(self.top2) > 0.15:
            self.committed = self.top2[0]
        elif gripper_distance(self.top2[0]) < 0.15:
            self.committed = self.top2[0]
        return self.committed or self.top2[0]

    def reanchor(self, obs, anchors):
        self.committed = None
        self.update(obs, anchors)

    def needs_reobserve(self):
        return (self.top2[0].p < 0.65 or margin(self.top2) < 0.15
                or self.tracker_conf < 0.3)
```

## 6. ARS：锚相对 5 步视觉伺服

### 6.1 坐标系

| 帧 | 定义 | 用途 |
|---|---|---|
| `base` | 机器人 base | 动作输出、EE 位姿 |
| `target` | 目标物体 | 抓取相对位姿 |
| `receptacle` | 容器/槽位/端口 | 放置/插入相对位姿 |
| `ee` | 夹爪基座 | 控制误差 |
| `wrist` | 腕部相机 | 2D IBVS |
| `head` | 头部相机 | 双目深度/全局定位 |

**规则：** 所有误差在同一帧里算；不要混用“base 系目标 + wrist 系误差”。

### 6.2 PBVS 粗调

```python
def pbvs_step(T_ee, T_target, T_target_ee_star, Kp, Kd, dt, prev_e):
    e = log_se3(inv(T_ee) @ T_target @ T_target_ee_star)
    de = (e - prev_e) / dt
    delta = clip(Kp * e + Kd * de, -DELTA, DELTA)
    return delta, e
```

- `log_se3`：旋转用 SO(3) log，平移直接取。
- `Kp`：平移 0.3–0.6，旋转 0.2–0.4。
- `Kd`：0.05–0.1；噪声大时降为 0。
- `DELTA`：插入 2–5mm/步；堆叠 5–10mm/步；自由空间 10–20mm/步。

### 6.3 IBVS 精调

```python
def ibvs_step(uv_cur, uv_des, K, Z, lam):
    e = uv_cur - uv_des
    L = interaction_matrix(uv_cur, K, Z)
    delta = -lam * pinv(L) @ e
    return delta
```

- 腕部内参 `K` 已知；`Z` 用头部双目/已知尺寸。
- 只控制平移 + 绕光轴小旋转；不要全 6D（噪声大）。
- 像素误差死区 1–2px；亚像素用插值。
- 当 `Z` 不可靠（透明/反光）时，退回 PBVS + 边缘/轮廓。

### 6.4 插入/接触相位

```python
def insertion_step(target, receptacle, ee, phase):
    z_t = target.axis
    z_r = receptacle.axis
    e_axis = cross(z_t, z_r)
    e_lat = lateral_error(target.tip, receptacle.opening, z_r)
    e_depth = dot(target.tip - receptacle.opening, z_r)

    if phase == "approach":
        return clip(0.5*e_lat + 0.3*e_axis, LIM_APPROACH)
    elif phase == "align":
        return clip(0.3*e_lat + 0.5*e_axis, LIM_ALIGN)
    elif phase == "insert":
        return clip(0.2*e_lat + 0.4*e_axis + 0.5*e_depth, LIM_INSERT)
    elif phase == "contact":
        return clip(0.1*e_lat + 0.2*e_axis + 0.3*e_depth, LIM_CONTACT)
```

**相位判定：**
- `approach`：距离 >5cm。
- `align`：距离 1–5cm；轴误差 >5°。
- `insert`：距离 <1cm；轴误差 <5°。
- `contact`：检测到阻力/位置误差上升/夹爪状态变化；无传感器时用“位置跟踪残差 + 速度下降”近似。

**接触段策略：**
- 降增益 50%；速度限 5mm/s；死区 0.5mm。
- 小螺旋搜索：`(x,y) = r(cosθ, sinθ)`，`r` 从 0.5mm 到 2mm；每圈 200ms；最多 3 圈。
- 失败 → 后退 2mm → 重对齐 → 重试；最多 2 次。
- 不假装有力传感器；不用电流（API 可能不给）。

### 6.5 延迟补偿

```python
def predict_target(T_target, twist, tau):
    if twist is None:
        return T_target
    return T_target @ exp_se3(twist * tau)

def estimate_tau(meta):
    rtt = meta.recv_time - meta.send_time
    return min(max(rtt / 2.0, 0.0), 0.2)  # 保守上限 200ms
```

- 静止物体：`twist=0`，不预测。
- 被抓取物体：用 EE twist 预测。
- RTT 抖动大：`tau` 取 p95；增益降 30%。
- 不用“未来图像”；只用当前图像 + 运动模型。

### 6.6 Chunk 与频率

| RTT | chunk | 伺服频率 | Kp | 备注 |
|---|---:|---:|---:|---|
| <50ms | 3–5 | 30Hz | 0.4–0.6 | 最佳 |
| 50–150ms | 5 | 30Hz | 0.25–0.4 | 默认 |
| 150–300ms | 8–10 | 15–30Hz | 0.15–0.25 | 保守 |
| >300ms | 10–15 | 10–15Hz | 0.1–0.15 | 只做稀疏修正 |

**注意：** API 的 chunk 是开环执行；ARS 只能在 chunk 边界更新。如果 chunk=5，30Hz 下每 166.7ms 一次修正；这和 RTT 是同一量级，所以增益不能大。

## 7. RAR：重锚定恢复

### 7.1 检测信号

| 信号 | 定义 | 阈值（起点） | 动作 |
|---|---|---|---|
| 静止目标残差 | `r_a = ||p_target(t) - p_target(t-1)||`，减去机器人运动 | >5mm/帧，连续 3 帧 | HOLD |
| 抓取后残差 | `r_g = ||T_target - T_ee T_ee_target*||` | >10mm | HOLD/REOBSERVE |
| 遮挡 | bbox 面积下降 >50% 或 `conf<0.3` | 连续 3 帧 | REOBSERVE |
| 人的手 | 肤色/大运动连通域接近目标 | 面积 >2% 图像 + 速度 >20px/帧 | HOLD |
| 位置跟踪残差 | `||q_cmd - q_state||` 上升 | >2× 基线 | 接触/受阻 |
| 超时 | 子目标耗时 > 预算 | 任务相关 | REPLAN |

**注意：** 不要试图训练“人的检测器”；用颜色/运动/残差就够了。SocialVLA 的语音/表情信号在本赛题不可用。

### 7.2 状态机

```text
SERVO
  ├─(r_a > θ, K 帧)──────────────▶ HOLD
  ├─(occlusion/conf low)─────────▶ REOBSERVE
  └─(timeout)────────────────────▶ REPLAN

HOLD
  ├─(200ms 稳定且人离开)─────────▶ REOBSERVE
  └─(人仍在/危险)────────────────▶ HOLD

REOBSERVE
  ├─(top1 p>τ_id, margin>τ_m)────▶ REANCHOR
  ├─(超时/找不到)────────────────▶ REPLAN
  └─(仍遮挡)─────────────────────▶ HOLD/REOBSERVE

REANCHOR
  ├─(更新 target/receptacle)─────▶ SERVO
  └─(更新失败)───────────────────▶ REPLAN

REPLAN
  ├─(WLA 新 plan)────────────────▶ SERVO
  └─(预算耗尽)───────────────────▶ ABORT/失败
```

### 7.3 重观察动作库

```python
REOBSERVE_ACTIONS = [
    ("wrist_back", 0.05),    # 腕部后撤 5cm
    ("wrist_left", 0.05),    # 侧移 5cm
    ("wrist_right", 0.05),
    ("wrist_tilt", 0.1),     # 倾斜 0.1 rad
    ("head_pan", 0.1),       # 头部/腰部微转
    ("wait", 0.2),           # 等待遮挡消失
]
```

**选择策略：**
- 如果目标被机械臂自身遮挡：腕部后撤/侧移。
- 如果目标被外部物体遮挡：头部/腰部微转，换视角。
- 如果目标被人手遮挡：先 HOLD，等人离开；不要硬动。
- 如果目标被移出视野：回到 keyframe 视角/扫描桌面。
- 每次重观察后重新跑 IPAT；最多 3 次。

### 7.4 伪代码

```python
class RAR:
    def detect(self, obs, target, ipat, last_cmd):
        if target is None:
            return "LOST"
        r_a = norm(target.p - self.prev_p) - robot_motion(obs, last_cmd)
        if r_a > 0.005 and self.consecutive > 3:
            return "MOVED"
        if target.area < 0.5 * self.prev_area:
            return "OCCLUDED"
        if ipat.tracker_conf < 0.3:
            return "LOW_CONF"
        if human_near(target, obs):
            return "HUMAN"
        if self.subgoal_time > self.budget:
            return "TIMEOUT"
        return None

    def transition(self, state, event):
        if state == "SERVO" and event in ("MOVED", "HUMAN"):
            self.hold_start = now()
            return "HOLD"
        if state == "SERVO" and event in ("OCCLUDED", "LOW_CONF"):
            return "REOBSERVE"
        if state == "SERVO" and event == "TIMEOUT":
            return "REPLAN"
        if state == "HOLD" and now() - self.hold_start > 0.2:
            return "REOBSERVE"
        if state == "REOBSERVE":
            if ipat.committed and ipat.top2[0].p > 0.65:
                return "REANCHOR"
            if self.observe_count > 3:
                return "REPLAN"
        if state == "REANCHOR":
            return "SERVO"
        if state == "REPLAN":
            return "SERVO"
        return state
```

### 7.5 安全

- HOLD 输出零速度/保持位姿；不要“边等人边动”。
- 人在工作空间内：不靠近；不高速；不做大范围扫描。
- 重观察动作限速/限幅；不碰桌面/容器。
- 超时/低置信：优雅失败，不硬追。
- 所有状态转换打日志；单任务通道回放。

### 10.1 任务组合（32 个）

| Tier | 任务 | 数量 | 主模块 | 目标 |
|---|---|---:|---|---|
| A 身份优先 | T04、T06、T09、T11、T15、T17、T21、T22、T27、T28、T29、T31 | 12 | RAG + IPAT | 指代/顺序/容器 +5–10pp |
| B 接触优先 | T01、T05、T10、T12、T13、T14、T19、T20、T23、T25、T26、T32 | 12 | ARS | 插入/挂/叠/拉链/锁 +5–10pp |

**为什么 C 类不强行加模块：** 长程/变形/动态任务的世界知识和 replan 更重要；硬加锚点可能让模型分心。C 类只做 RAR 的安全 HOLD 和超时回退。

### 10.2 投入优先级

```text
priority_t = q_t * Δ_t / cost_t
```

- `q_t`：失败发生在身份/接触/恢复的比例（先验，单任务通道后更新）。
- `Δ_t`：模块条件增益（A/B 差值）。
- `cost_t`：工程/评测成本（锚图/标定/调参）。

先做 A 类中 `q_t` 高、`cost_t` 低的 3–5 个；再做 B 类 3–5 个；不要一次铺 24 个。

| 保守 | 8 个任务 +8pp | +2.0pp |

| 基准 | 24 个任务 +8pp | +6.0pp |
| 乐观 | 24 个任务 +12pp | +9.0pp |

**注意：** 这些是设计目标，不是承诺；A/B 类有重叠，不要重复加。正式赛 320 trials 的 SE≈2.6–2.8pp；+6pp 是约 2.2σ，仍可能是噪声，所以要用配对设计/重复实验。

## 11. 风险、合规与安全

### 11.1 风险表

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 单模型违规 | 中 | 高 | RAG/IPAT/ARS/RAR 无学习权重；PRT 只微调同一 WLA |
| 指代后验错误 | 中 | 高 | top-2 延迟承诺；负锚点；回退 VLA |
| 跟踪漂移/遮挡 | 高 | 中 | 置信度阈值；RAR；重识别 |
| 透明/反光 | 高 | 中 | 边缘/颜色/已知尺寸；不迷信深度 |
| RTT 抖动 | 中 | 中 | 小步/高阻尼；RTT 大时开环 |
| 标定误差 | 中 | 中 | G0；每机器人重标；已知尺寸校验 |
| 重观察耗时 | 中 | 中 | ≤3 次/任务；每次 ≤400ms；超时 replan |
| 人干扰误触发 | 中 | 中 | 残差 + 面积 + 置信度联合；≤5% |
| 数据泄漏 | 中 | 高 | 按 session/物体/背景分组；相邻帧不跨 split |
| 评测噪声 | 高 | 中 | 配对 A/B；bootstrap；320 trials |
| 预览榜单误导 | 高 | 中 | 只当难度信号；不逐任务过拟合 |
| 语音演示越界 | 低 | 中 | 离线/演示不进入评分；不混赛道 |
| 提交次数限制 | 中 | 高 | 邮件确认；单任务通道先验证；保守提交 |

### 11.2 合规表述（给官方）

> 我们的提交只部署一个学习模型：UnifoLM-WLA-1.0 微调后的单一 checkpoint。RAG 是人工审阅的符号 JSON；IPAT 使用已标定双目几何、颜色/形状/跟踪等确定性算法；ARS 是确定性控制器；RAR 是状态机。它们都不包含学习权重，不调用第二个在线 VLA/LLM/分割大模型。PRT（如使用）只对同一 checkpoint 的 action head 做离线微调。语音/ASR/TTS 只在离线评测或演示中使用，不进入评分路径。

### 11.3 安全

- 限速/限幅；工作空间/桌面净空；最大重试。
- 身份后验低/检测到人 → HOLD/重观察/回退；不硬追。
- 碰撞预测 → hold。
- 超时/低置信优雅失败；不追求“必须完成”。
- 真机测试先在单任务通道、低速、空场景。
- 不记录/上传 token；不泄露 API 密钥。
