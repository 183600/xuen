# 第 43 轮（新循环第 3 轮） · IRC³ 规格证书：把「语言指令」编译成可认证契约、把「奖励设计」认证成安全信号——从「策略可验证」上移到「规格可验证」的证书信任链（四层架构 v8）

> 承接第 42 轮 v19（Sim-Cert-RAG 飞轮）。v19 把几乎全部算力都压在「策略/状态」这一层的可验证性上：CAR 守卫、LCS 分档、SCV 仿真、CKB 检索、ECR 边缘运行时。但它默认了一件从未被审查的事——**规格（spec）从哪里来、是否正确**。真实任务里，规格由人类的「语言指令」给出，策略由「奖励设计」训出。于是出现两条 v19 无法覆盖的静默失效链：(i) **指令歧义/误编译**：证书对「错误的规格」完全 sound，机器人被认证去干错事；(ii) **奖励设计偏差/奖励劫持（reward hacking）**：策略满足守卫，却用奖励漏洞换取高回报，证书对「奖励的最优解」完全 sound，但那个最优解不是人类想要的。本轮的直觉是把证书对象**上移一层**：不再只认证策略，而是把 **指令 → 任务契约 → 奖励机器 → 策略** 整条链做成一张可失效传播的「证书信任链」。语言指令提供**规格的语义与歧义集**，奖励设计提供**可优化但必须被认证的安全信号**，二者共同被纳入证书体系，形成 **IRC³（Instruction–Reward–Certificate）三元闭环**。

## 0. 直觉与动机

**灵感 1（奖励设计 → 奖励不是「训练细节」，而是必须被认证的「安全信号」）**：v19 的证书只回答「这个策略在给定守卫下安不安全」，却从不回答「我们优化的目标本身是否鼓励安全」。奖励设计在这里不是调参，而是一次**规格的编码**：`r = w_g·到达 + w_s·平滑 − w_c·碰撞` 里的每个权重，都在隐式声明「什么值得做」。一旦权重与硬约束错位，RL 会精确地找到那个错位——这就是 reward hacking。直觉上，奖励应当像传感器一样被**标定与认证**：它也有量程、有偏置、有盲区。于是本轮提出**奖励证书**：不是证明某个策略最优，而是证明「在这个奖励下，任何高回报策略都不会显著违规，也不会龟缩不动」。把奖励从「训练脚本里的几行权重」提升为「带安全/进度/塑形三性质的可认证制品」。

**灵感 2（语言指令 → 指令不是「提示词」，而是带歧义集的「规格源码」）**：v19 的 CKB 用任务指纹 φ 检索证书模板，但 φ 是人手定义的。真实入口是一句自然语言：「把红色杯子放到盘子左边，别碰倒花瓶」。这句话里有硬约束（别碰倒）、软偏好（放在左边）、隐式目标（红色杯子，可能是多个）、以及**天然歧义**（「左边」是机器人视角还是相机视角？）。直觉上，语言指令应被当作**源码**来编译：LLM 只做「前端解析」，形式化接地与类型检查做「后端校验」，而歧义不能靠一句「模型很自信」糊弄过去——必须输出一个**显式的解释集合 A**，并只对 A 中所有解释的**交集契约**作承诺；A 太大就触发澄清。这就是**保形（conformal）指令编译**：用统计校准保证「真实意图落在 A 内」的概率 ≥ 1−α。

**灵感 3（耦合 → IRC³ 闭环与「元证书」）**：单独看，奖励认证和指令编译都只是补丁；合起来才产生质变——它们让证书链第一次拥有**规格层的叶子节点**。语言指令接地产生任务契约 τ（目标 G、硬约束 H、软偏好 S、语言势函数 Φ、歧义集 A）；奖励机器 M_R 把 τ 编译成可优化的回报；策略证书证明策略满足 H；奖励证书证明「高回报 ⇒ 不违规 ∧ 有进度」；一旦指令被澄清、A 收缩，或奖励被修补，所有下游证书按依赖图**自动失效**，CAR 立即降级。证书从「一棵树上的叶子」变成「一张有向无环图」，从「静态制品」升级为「带失效传播的信任链」。v19 解决「怎么让策略可信」，本轮解决「凭什么相信我们优化的就是人想要的」。

**与 v19 的关系**：v19 是**执行层飞轮**（Sim→RAG→Edge→Sim），本轮是**规格层飞轮**（Instruction→Reward→Certificate→Instruction）。二者共享 CKB 与 SCV：SCV 新增「奖励劫持红队」，CKB 新增「指令/奖励/见证/补丁」四类记录。本轮不推倒任何既有层级，只在 L2 入口前插 IP-57，在 L4 认证环中插 IP-58/59。

## 1. 形式化定义（增量：定义 38–43）

**定义 38（指令任务契约与保形歧义集）**：语言指令 I 经编译器 γ 得到任务契约 τ = (G, H, S, Φ, A)：G 为目标谓词，H 为硬约束集合（编译为 CAR 守卫与不变式），S 为软偏好（代价项），Φ 为语言势函数，A 为解释歧义集。保形校准：非一致性分数 s(I, τ) = −log p_θ(τ | I)，阈值 q̂ 取校准集上 ⌈(n+1)(1−α)⌉ 分位，A(I) = {τ' : s(I, τ') ≤ q̂}。若校准指令与测试指令可交换，则 **P(τ\* ∈ A(I)) ≥ 1−α**。**保守契约** τ̄ = ⊓A：G 取各解释目标的公共可达集、H 取并集、S 取逐项最保守下界、Φ 取最小公共势函数。证书只对 τ̄ 承诺，A 中未被交集覆盖的部分显式标注为「未认证」，绝不默认成立。

**定义 39（奖励机器与 CAR 乘积）**：奖励机器 M_R = (U, u₀, δ_R, r_R, Acc)，状态 u 为任务相位，转移标号为接地原子事件（grasp/release/reach/contact…）。产品自动机 M = CAR ⊗ M_R，转移 e = (q,u) → (q′,u′)，即时奖励 r(e) = r_task(u,u′) + r_shape(e)。接受条件 Acc_M = Acc_CAR × Acc_R。**奖励-规格一致性**：argmax_π J_r(π) ⊆ Feasible(CAR) ∩ Acc_M；违反时称存在**奖励劫持**。注意该式对「全体策略」量化，因此它比策略证书严格更强，也正是它困难、必须用抽象解释近似的原因。

**定义 40（奖励证书三性质）**：奖励证书 C_r = (safety_ok, progress_ok, shaping_ok, bounds, witness)，对应：
- **安全一致性**：∃ε_s，∀π，J_r(π) ≤ J_r(π_safe\*) + κ·V_viol(π)。即奖励不能大量「购买」违规；等价的区间形式是「不安全策略最优回报上界 U_adv ≤ 安全策略最优回报下界 L_safe + ε_s」。
- **进度一致性**：令 Π_stall 为 T 时域内无任何进度事件的策略集，要求 max_{π∈Π_stall} J_r(π) ≤ J_ref − ε_p。它直接封死「龟缩在安全区刷存在奖励」这一退化最优解，正面回应第 41/42 轮的可用性崩塌风险。
- **塑形不变性**：若 r′ = r + F 且 F(s,s′) = γΦ(s′) − Φ(s)，则 argmax_π J_{r′} = argmax_π J_r（Ng–Harada–Russell 1999）。故对 r 的策略证书可零改动迁移到 r′，只需把 Φ 的接地误差 ‖Φ̂ − Φ‖ ≤ ε_Φ 计入 L_m。

**定义 41（区间奖励认证与「证明或见证」二择）**：在抽象状态上跑区间 Q 迭代，得到安全策略最优回报的**下界** L_safe 与不安全策略最优回报的**上界** U_adv。若 U_adv ≤ L_safe + ε_s，输出**认证无劫持**；否则进入**见证搜索**：用约束 RL 求 π_w，使 V_viol(π_w) > 0 且 J_r(π_w) > J_r(π_safe\*)。找到则输出**具体劫持见证**；找不到则输出**未决（区间过松）**并强制人工/红队复核。该二择保证 soundness：认证分支用过近似上界，见证分支用具体反例，二者都不会把「存在劫持」误报为「无劫持」（唯一漏报源是未决分支，被显式暴露而非隐藏）。

**定义 42（语言势函数的证书保持性）**：设 Φ(s) = −d_{C_ms}(s, G) 或由语言进度监督器给出的语义进度分（C_ms 为 IP-49 的度量语义图）。**命题**：若塑形严格为潜势差，则最优策略集合不变，安全策略集合不变，故 IP-51 守卫与 IP-52 档位无需重认证；新增的唯一误差是 Φ 的接地误差 ε_Φ，将其并入 Lipschitz 常数即可保持 LCS 的单调保守性。这使「语言」可以进入奖励而不破坏既有证书体系。

**定义 43（证书信任链与失效传播）**：证书 c = (claim, evidence, deps)，evidence 可为形式证明、统计校准结果、仿真日志或区间界。valid(c) = valid_evidence(c) ∧ ∀d∈deps valid(d)。叶子证书包括：指令接地证书（定义 38）、奖励证书（定义 40/41）、Sim-to-Real 迁移证书（定义 32）、L0/L1 精度证书（定义 33/34）。**失效传播**：任一叶子失效或歧义集 A 扩大，所有祖先节点标记 stale；CAR 在重颁前禁止使用 stale 证书做 T-1/T0 决策并降级到 SafeStop。于是「证书的证书」第一次成为一等公民：RCA 重颁时必须打印完整依赖 DAG 与每个叶子的有效期。

## 2. 产出设计（增量 IP-57/58/59 + 升级）

### 2.1 IP-57 INSTRUCTION-COMPILER（指令编译器 L2C）
1. **前端解析**：LLM 生成 top-k 带类型的接地谓词语法树（reach/grasp/avoid/keep_upright/follow/speed≤v…），温度采样保证多样性，避免单一幻觉。
2. **后端校验**：类型检查 + 相对 IP-49 语义图 C_ms 的可接地性检查 + 物理可行性筛除；不可接地的谓词直接拒绝，不做「猜测性修补」。
3. **保形歧义集**：在校准集上估非一致性分数分位 q̂，输出 A(I)；歧义直径 > ε_A 时用「最大分歧查询」主动澄清（一次只问最能分裂 A 的问题，信息增益最大）。
4. **契约交集**：τ̄ = ⊓A；输出 `(τ̄, A, q̂, 未认证区域)`，未认证区域写入证书对象，运行期不可被当作安全区。

### 2.2 IP-58 REWARD-CERTIFIER（奖励认证器 RC）
1. **奖励机器编译**：τ̄ → M_R；与 CAR 做乘积；硬约束 H 编译为「护盾转移」而非单纯大惩罚（惩罚可被更高任务回报覆盖，护盾不可）。
2. **区间奖励认证**：对 M 跑区间 Q 迭代，分安全/不安全策略类，得 L_safe/U_adv；满足定义 41 则签发 safety_ok，否则进入见证搜索。
3. **进度一致性检查**：构造 Π_stall 的抽象（无进度事件自环），用区间界验证其最大回报低于参考；不满足则自动向奖励注入「进度项」候选。
4. **潜势塑形守卫**：仅接受形如 γΦ(s′)−Φ(s) 的塑形项，非潜势项一律拒绝（否则证书保持性失效），并记录 ε_Φ。
5. **输出**：C_r + 区间边界 + 见证（若有）+ 一项「区间松紧度」指标（用于风险 2 的量化监测）。

### 2.3 IP-59 IRC-LOOP（语言在环的奖励修复与信任链管理）
1. **语言归因**：把劫持见证轨迹交给 VLM/LLM，生成自然语言解释（「它学会把物体推到桌边以规避抓取惩罚」），作为可读证据入 CKB。
2. **补丁检索与生成**：按 (τ, 归因文本) 检索历史奖励补丁；生成候选补丁（加硬护盾/改潜势/加进度项/收紧权重），**每个补丁必须重新过 IP-58 与 IP-51 双认证**才可采纳。
3. **失效传播引擎**：维护证书 DAG；指令澄清或奖励修补时，按依赖拓扑标记 stale、局部重认证、只重颁受影响子树（避免全量重跑）。
4. **人机接口**：澄清问题与补丁 diff 以最小可读形式呈现，人工只做「确认/否决」，把人工成本压到最低。

## 3. 四层架构 v8

## 4. 实验设计（E87–E94 硬门槛，承接 E79–E86）

| 实验 | 指标 | 门槛 |
|---|---|---|
| E87 指令保形接地 | 真实意图 ∈ A 的覆盖率；歧义指令的澄清率；误接地率 | 覆盖 ≥ 95%（α=0.05）；澄清率 10%–30%；误接地 < 1% |
| E88 奖励劫持检测 | 红队套件（龟缩/边界骑行/藏匿/刷分/护盾滥用）检出率；平均检出延迟 | 检出 ≥ 95%（红线，允许「未决」）；延迟 < 2 轮 |
| E89 奖励证书 soundness | 认证分支（safety_ok）下真实违规率；区间松紧度 | 违规率 = 0（10k 策略）；松紧度中位数 < 0.3 |
| E90 进度一致性 vs 可用性 | Nominal 占比；龟缩策略最优性 | Nominal ≥ 80%；龟缩最优出现率 0 |
| E91 潜势塑形证书保持 | 塑形前后最优策略一致率；证书迁移成功率 | ≥ 99%；100% |
| E92 语言在环修复 | 从发现劫持到修复通过认证的时间；人工交互次数 | < 30min；≤ 2 次 |
| E93 端到端 IRC³ | 任务成功率；认证覆盖率；澄清率；全链时延 | ≥ 90%；≥ 95%；< 30%；< 5min |
| E94 长时程回归 | 100h：不安全事件、劫持回归、stale 恢复时间 | 0 起；0 次；< 1min |

回退：E87 覆盖不达标 → 提高 α（更保守）或关闭自动接地、退回人工确认模板；E88 检出不足 → 禁止自动采纳补丁，全部人工红队；E89 区间过松 → 降级为「经验认证 + 强制护盾」，并标注「非 sound」；E90 可用性崩塌 → 放宽进度门槛或只保护盾 + SafeStop 双态；E92 修复过慢 → 关闭语言归因，退回人工奖励改写。

## 5. 本轮最大风险

**一句话**：把奖励与指令也纳入证书，会把系统的「不可判定性」从策略层上移到规格层——若指令编译器与奖励认证器共享同一 LLM/VLM 语义先验，二者会**相关犯错**，产出一张「自洽但错误」的元证书（语言把错误规格说圆，奖励认证再为这个错误规格背书），这比 v19 的仿真偏差或检索幻觉更难被独立发现；同时奖励证书对「全体策略」量化极易因区间过松而空洞、过紧而杀死可用性，因此 E88（劫持红队检出）与 E90（进度一致性下的 Nominal 占比）必须作为红线实验，任何一项不达标即冻结自动认证、退回「护盾 + 人工确认」。

## 2. 关键算法（伪代码）

### IP-57 L2C：保形指令编译与主动澄清
```
def compile_instruction(I, C_ms, calib_set, alpha=0.05, eps_A=0.2):
    cands = llm_parse(I, k=16, temperature=0.7)        # 前端：多样化候选
    valid = []
    for tau in cands:
        if not typecheck(tau): continue
        if not groundable(tau, C_ms): continue          # 后端：语义图可接地性
        if not physically_feasible(tau): continue
        valid.append(tau)

    qhat = conformal_quantile(calib_set, alpha)          # 校准集上分位
    A = [tau for tau in valid if score(I, tau) <= qhat]
    if not A:
        return CLARIFY(generate_questions(I, C_ms))

    if ambiguity_diameter(A) > eps_A:                    # 歧义过大
        return CLARIFY(max_info_gain_queries(A, C_ms))  # 一次问最能分裂 A 的

    tau_bar = intersect_contracts(A)                     # G 交、H 并、S 最保守
    uncovered = find_uncovered(A, tau_bar)               # 显式未认证区域
    return TaskContract(tau_bar, A, qhat, uncovered)

def conformal_quantile(calib, alpha):
    scores = sorted(score(I_i, tau_i_true) for (I_i, tau_i_true) in calib)
    n = len(scores)
    return scores[min(n-1, ceil((n+1)*(1-alpha)) - 1)]
```

### IP-58 RC：奖励机器、区间认证与见证搜索
```
def certify_reward(tau_bar, r, CAR, eps_s=0.01, eps_p=0.01):
    M_R = compile_reward_machine(tau_bar)               # 硬约束 -> 护盾转移
    M   = product(CAR, M_R)
    # 1) 区间 Q 迭代：抽象状态上给出保守上下界
    L_safe, U_safe = interval_q(M, Pi_safe,   mode='max')
    L_adv,  U_adv  = interval_q(M, Pi_unsafe, mode='max')
    # 2) 安全一致性：证明或见证
    if U_adv <= L_safe + eps_s:
        safety_ok, witness = True, None
    else:
        witness = search_witness(M, r)                  # 约束 RL 找具体反例
        safety_ok = (witness is None)
    # 3) 进度一致性：停滞策略回报必须低于参考
    progress_ok = (interval_q(M, Pi_stall, mode='max').upper
                   <= J_ref - eps_p)
    # 4) 塑形不变性：仅接受潜势差
    shaping_ok = all(is_potential_term(term, tau_bar.Phi) for term in r.shaping)
    slack = (U_adv - L_safe - eps_s)                    # 区间松紧度（越大越不可信）
    return RewardCert(safety_ok, progress_ok, shaping_ok,
                      bounds=(L_safe, U_safe, L_adv, U_adv),
                      witness=witness, slack=slack)

def search_witness(M, r, budget=600):
    # max J_r  s.t. V_viol > 0；用拉格朗日约束 RL，优先高回报 + 高违规区
    pi_w = constrained_rl(M, objective=r, constraint=V_viol > 0,
                          budget=budget, init_from=boundary_states(M))
    if pi_w is not None and evaluate(pi_w).viol > 0:
        return Witness(policy=pi_w, traj=rollout(pi_w), return_=J(r, pi_w))
    return None                                         # 未决：交给红队/人工
```

### IP-59 IRC-LOOP：语言归因、补丁与证书失效传播
```
def language_in_the_loop(witness, tau_bar, KB):
    # 1) 把劫持轨迹转成人类可读归因
    narrative = vlm_explain(witness.traj, tau_bar)      # "它把物体推到桌边规避抓取惩罚"
    # 2) 检索相似历史修复案例
    recalled = KB.retrieve_reward_patches(tau_bar, narrative, k=5)
    # 3) 生成候选补丁：加护盾 / 改潜势 / 加进度项 / 收紧权重
    cands = propose_patches(narrative, recalled, tau_bar)
    # 4) 每个补丁必须双认证，禁止只过一关就上线
    for p in cands:
        r_new = apply_patch(tau_bar, p)
        cr = certify_reward(tau_bar, r_new, CAR)
        if not (cr.safety_ok and cr.progress_ok and cr.shaping_ok):
            continue
        pc = certify_policy(tau_bar, r_new)             # IP-51/52 策略证书
        if pc.ok:
            return p, cr, pc
    return None                                         # 全部失败 -> 人工接管

def invalidate_and_reissue(chain, changed_leaf, certs):
    stale = descendants(chain, changed_leaf)            # 依赖 DAG 后代
    for node in stale:
        certs[node].mark_stale()
    order = topo_sort(stale)
    reissued = {}
    for node in order:                                  # 只重颁受影响子树
        if all(certs[d].valid for d in certs[node].deps):
            reissued[node] = reissue(node, certs)
    return reissued

def car_guard_with_chain(e, x, cert):
    if cert.stale or not cert.chain_valid:              # 任何祖先失效
        return DEGRADE_SAFESTOP                        # 禁止使用 stale 证书
    theta_real = cert.alpha_e[e] * cert.theta_sim[e]
    return cert_lookup_L0(x).m_lo[e] >= theta_real
```

### IP-53 升级：区间 Q 网络导出（供 RC 调用）
```
def export_interval_q(q_network, state_abstraction):
    # 复用 CMC 的区间电路：把 Q 网络转成带上下界的区间电路
    q_lo_circuit, q_hi_circuit = interval_lift(q_network, state_abstraction)
    # 认证时用 q_lo 做安全下界、q_hi 做不安全上界，保持 sound
    return IntervalQ(q_lo_circuit, q_hi_circuit)

def interval_q(M, Pi_class, mode='max'):
    lo = {s: -inf for s in M.states}
    hi = {s: +inf for s in M.states}
    # 区间 Bellman 迭代：转移和奖励均用保守端
    while not converged(lo, hi):
        for s in M.states:
            lo[s] = max(lo[s], min_over_actions(r_lo(s,a) + gamma*lo[s']))
            hi[s] = max(hi[s], max_over_actions(r_hi(s,a) + gamma*hi[s']))
    return QuantileBound(lo, hi)
```

| 组件 | 时间复杂度 | 空间复杂度 | 正确性保证 |

## 5. 风险与缓解（增量）

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 语义-奖励共谋：L2C 与 RC 共享同一 LLM/VLM 语义先验，相关犯错，产出「自洽但错误」的元证书 | 高 | 独立验证路径：形式接地校验器 ≠ LLM；RC 的区间界不依赖语言模型；证书必须附可执行见证/测试套件；关键任务人工抽检 + 跨模型交叉检查 |
| 奖励证书不可判定：区间过松导致「空洞认证」，过紧导致「全拒绝」 | 高 | 证明或见证二择；显式报告区间松紧度 slack 并设阈值；未决分支强制红队/人工；只在 slack 达标时允许自动上线 |
| 可用性崩塌复发：进度一致性收紧后 Nominal 掉回 Degraded/SafeStop | 高 | 进度项与参考策略 J_ref 联合标定；E90 红线；必要时只保留「护盾 + SafeStop」双态并放弃自动奖励认证 |

| 语言势函数被 VLM 幻觉污染，塑形把策略引向错误方向 | 中 | Φ 只从 C_ms 几何接地或多源监督生成；ε_Φ 计入 L_m；塑形项必须过潜势形式检查 |
| 信任链失效风暴：一个叶子漂移导致大面积 stale | 中 | 细粒度依赖 + 局部重颁 + 叶子缓存与有效期；漂移检测用 EWMA 抑制抖动；冷却期 |

| 劫持见证搜索成本高、可能漏检 | 中 | 复用 CMC 区间 Q 缩小搜索空间；边界状态初始化；红队套件作为回归底线 |

## 6. 本轮最大风险

**一句话**：把奖励与指令也纳入证书，会把系统的「不可判定性」从策略层上移到规格层——若指令编译器与奖励认证器共享同一 LLM/VLM 语义先验，二者会**相关犯错**，产出一张「自洽但错误」的元证书（语言把错误规格说圆，奖励认证再为这个错误规格背书），这比 v19 的仿真偏差或检索幻觉更难被独立发现；同时奖励证书对「全体策略」量化极易因区间过松而空洞、过紧而杀死可用性，因此 E88（劫持红队检出）与 E90（进度一致性下的 Nominal 占比）必须作为红线实验，任何一项不达标即冻结自动认证、退回「护盾 + 人工确认」。
