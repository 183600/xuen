# 第 13 轮 · FLEET-PORTRAIT：多机评测把「一个模型」拆成 N 个未知端口；先在线标定每个端口，再谈最后 3 厘米

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是灵感循环第 3 轮（状态文件第 12 轮之后），三个词是「多机评测」「排行榜」「大语言模型」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是修正 CHUNK-SERVO 的一个隐含前提：**上一轮假设相机几何已知、端口只有一个；多机评测下，每台机器人、每个端口的几何/动作系/延迟都未知。** 于是把「标定」从离线准备变成在线能力，把「任务卡」从人工规则变成 LLM 离线编译，把「榜单」从优化目标变成噪声测量。

## 0. 先给结论：榜单是合成的，端口是真的；先把「每台机器人」标定出来

截至 2026-10-31，公开榜单仍是**预览数据**：榜首 MolmoAct2 29.7%，第 8 名 GR00T N1.5 20.5%，头尾只差 9.2pp；`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，`step_score ~ success_rate` 的 R² > 0.999999，256 个任务成功率中 232 个不是 10% 的整数倍，`runs.html` 的 256/256 条记录也来自同一份生成数据。**它不能告诉我们真实的任务难度，也不能告诉我们真实的多机方差。**

但规则里有一件真事：评测跨 **N 台机器人**，提交要从 **8765** 起暴露 N 个连续端口，每端口独立交互、`reset()` 隔离。官方 API 又不提供 `camera_info`、深度、力/触觉，只有四路 RGB。于是每台机器人对策略来说都是一个**未知端口**：

1. 头部双目 `fx` 在 32 个数据集里是 **186.03–296.15 px**，基线 **46.72–64.86 mm**；线上不告诉你当前端口是哪一组。
2. 腕部彩色 `fx` 很稳（**432.89–437.49 px**），但数据集里才有；线上没有内参，且腕部到 EE 的手眼变换未知。
3. `pivot`/EE 动作系的精确语义、TCP 偏置、控制频率、RTT/抖动，线上都不保证与训练数据一致。
4. 真实机器人评测的方差可以大到 **0%–100%**（RoboChallenge，arXiv 2510.17950）；硬件偏移可以让 VLA 从接近 100% 掉到接近 0%（Self-Adaptive VLA，arXiv 2609.30092）。

所以本轮押注不是「再训一个更大的 VLA」，也不是「把榜单任务排名当难度表」，而是：

> **FLEET-PORTRAIT：把每个端口当成一台独立的、未标定的机器人；用任务本身的正常运动被动估计头部姿态、腕部几何、桌面平面、动作系偏置和延迟；用 LLM 离线编译的 32 张任务卡告诉控制器“现在该看哪个特征、该信多少、失败怎么退”；用 FLEET-UVS 在最后 1–2 cm 做低维、正则化的在线图像雅可比修正；用 ROBUST-SUBMIT 把有限的正式评测当成带方差的投资组合，而不是追合成榜单。**

一句话：**先把 N 个端口的几何/时序标定出来，再把最后 3 厘米闭环；标定不是预备实验，而是任务执行的一部分。**

三个可验证创新点（不是三个宏大名目）：

1. **FLEET-PORTRAIT**：每端口被动指纹——头部姿态由 `lower_body` 恢复，腕部用标称 K + 在线手眼修正，桌面平面/动作系偏置/延迟各自估计并带置信度；跨 episode 保留，但任务状态严格隔离。
2. **TASK-AS-CALIBRATION + FLEET-UVS**：不额外做标定动作；用任务卡标记的“可标定阶段”（接近、对位、抓取、放置）积累 `(ΔEE, Δ图像特征)` 样本；从标称雅可比初始化，只在线修正低维残差，正则化 + 置信度门控，避免 RLS 在坏初值下发散。
3. **TASK-CARD + ROBUST-SUBMIT**：LLM 只在离线把 32 条任务说明/演示编译成结构化任务卡（阶段、特征、成功谓词、恢复动作、可标定性）；在线只查静态 JSON，不跑第二个模型；正式评测用配对 A/B、bootstrap 下界和 CVaR 选 checkpoint，不追合成榜单的任务排名。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **多机评测** | 每端口指纹（头部姿态/腕部手眼/桌面平面/延迟）；端口级置信度；`reset()` 只清任务态、不清机器人指纹；共享 VLA、独立控制器 | 不假设所有端口同一台机器人；不跨端口共享任务观测；不把 N 端口做成 N 个模型 |
| **排行榜** | 320 trials 的 SE≈2.4pp；头尾 9.2pp；合成榜单只当预览上限；配对 A/B、bootstrap LCB、CVaR、先交安全基线锁 tie-break | 不把 32 个合成任务成功率当难度表；不为榜单排名过拟合；不把 +1–2pp 当结论 |
| **大语言模型** | 离线任务卡编译器：阶段/特征/成功谓词/恢复/可标定性；静态 JSON 上线；用 VLA 自己的 text encoder 做任务匹配 | 不在线跑第二个 LLM/VLM；不让 LLM 直接输出关节动作；不让 LLM 在环内做安全关键决策 |

## 1. 本轮新核实的事实（只列会改变方案的）

### 1.1 规则与流程：多机、N 端口、计分/不计分两种测试

官方参赛手册（中文/英文两版，2026-10-28 抓取，2026-10-31 复核）仍明确：

- 所有任务须基于**同一模型**完成，不得混合多个模型；模型类型不限（World Model、VLA 均可）。
- 32 个任务，每任务 10 次独立运行；5 类泛化各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
- 单次真机执行上限 **180 s**；排名先看 32 任务总平均成功率，成功率相同看总平均步骤分，再相同看更早提交。
- 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态必须隔离。
- 另有**不计分的单任务测试通道**；官网个人页新增「提交测试 / 预约评测时段」，但大量内容仍显示「即将发布」。

**对方案的约束**：FLEET-PORTRAIT 必须每端口独立、CPU 轻量、不抢 GPU；VLA 是唯一学习模型；在线不允许第二个学习模型；端口指纹可以跨 episode 保留，但任务观测/任务状态不能跨端口共享。

**重要修正（推翻第 12 轮的一个前提）**：`wrist_left/right.color` 在 `meta/info.json` 里**有** `camera_matrix` 和 `dist_coeffs`；腕部 IR1/IR2 还有双目外参（示例基线 **18.05 mm**）。第 12 轮「腕部没有内参、必须先做棋盘格标定」的判断错误。正确结论是：

- 腕部**彩色内参**有标称值，且跨任务很稳（`fx` 432.89–437.49，标准差 1.34 px）；线上即使不给，也可以用 32 个数据集的稳健中位数做先验。
- 腕部真正未知的是**彩色相机到 EE 的手眼变换**、彩色与 IR 的差异、以及当前端口的安装偏差；这些可以在线估计，不需要棋盘格。
- 头部双目内参跨任务差异很大：`fx` **186.03–296.15 px**，基线 **46.72–64.86 mm**；线上不提供，必须靠机器人状态恢复姿态，不能把某个数据集的 `fx` 当常数。
- 头部彩色/双目是 `rectified: true`；但线上只有 RGB，没有双目视差，也没有 depth。**不要把“数据里有双目”误当成“线上能拿深度”。**

**头部位姿的实证**：`state_d435` 是头相机在 base 系的 6D 位姿；`lower_body[-3:]` 与 `waist_state_joint` 一致，线上 API 给 `lower_body`。我们用 HangCup 的 24 个随机 offset 页、共 **2,400 帧**做了试点拟合：

|---|---:|---:|---:|---:|
| x | 0.999946 | 0.00016 m | 0.999972 | 0.00011 m |
| y | 0.999836 | 0.00031 m | 0.999840 | 0.00030 m |
| z | 0.999252 | 0.00012 m | 1.000000 | 0.00000 m |
| roll | 0.999604 | 0.00078 rad | 0.999884 | 0.00043 rad |

这支持一个强结论：**头部相机相对 base 的位姿，在当前数据里几乎是腰部 3 关节的确定性函数**；线性模型已经把位置误差压到亚毫米、姿态误差压到毫弧度。它是 HangCup 单任务的试点，不是 32 任务全量结论；G1 门要做全量/留任务验证。若全量通过，线上就能在不知道头部内参的情况下，至少恢复**头部姿态**；头部内参/尺度再用腕部米制运动或演示先验补。

不可用证据（B 级，来自公开 JSON/页面的回归与统计）：

### 1.4 官方基线与头部方案：大模型这件事已经做完，剩下的是执行层的“最后一厘米”

- **UnifoLM-WLA-1.0**：6B 参数，约 2,500 小时真机数据，64 个任务；动作专家默认 `chunk_size=30`、`target_fps=30`，4 步扩散去噪；冻结 VLM，只训 DiT action head + robot-state projector，**单张 24GB GPU 可微调**；统一动作 **54 维**、状态 **60 维**。
- 挑战赛 `ee` 动作是 **2×6 EE + 2×1 gripper + 7 pivot = 21 维**；WLA 的 54 维需要 adapter：EE 相对动作 compose 到当前绝对位姿，gripper 直通，pivot 从 base/waist/height 组合。**`pivot` 语义是否与挑战赛一致，必须先用 `example_env.py`/单任务通道验证。**
- 榜单头部模型家族：MolmoAct2、WALL-OSS-0.5、DreamZero、Spirit-v1.5、DM0、π0.5、GigaBrain-0、GR00T N1.5；路线覆盖 action reasoning、4B VLA、14B video world-action、开放世界 VLA、世界模型生成数据、通用人形 VLA。共同点仍是 **action chunk 开环执行**；世界模型解决“想象未来”，不解决“现在偏了 2 mm”。
- **战略结论**：不要从零训 6B/14B；用官方 WLA Base 做 action-head 微调，把省下的算力投到**每端口标定、执行层闭环、单任务评测**。官方 WLA 是否覆盖挑战赛 32 任务、是否直接适配 API，必须实测，不能假设。

### 1.5 外部证据：真实机器人评测的方差，首先来自硬件、测试者和延迟

这轮补了四类外部证据，都是“方向性证据”，不把单篇论文的具体数值当挑战赛结论：

| 工作 | 关键事实 | 对本方案的启示 |
|---|---|---|
| **RoboChallenge**（arXiv 2510.17950） | 同一套道具/任务/模型，真实成功率可以从 0% 到 100%；测试者（熟练/不熟练/自适应）本身造成显著差异；Table30 用 10 rollouts/任务 | 真实评测的方差不是小噪声；必须配对、分层、报告置信区间；端口/测试者差异可能大于模型差异 |
| **Self-Adaptive VLA**（arXiv 2609.30092） | 执行器偏置/关节编码器偏移可让 VLA 从近 100% 掉到近 0%；用自身 rollout 上下文迭代补偿，单次恢复 46–49%，6 次 ensemble 恢复 80–84% | 硬件偏移是第一阶问题；在线自适应有效，但需要“试错/上下文”；我们的端口指纹 + 低维残差是更轻的版本 |
| **ManipArena**（arXiv 2603.28545） | 真实评测要控制感知噪声、接触动力学、延迟、标定误差；server-side 推理；一模型全任务；π0.5 约 110ms/step，DreamZero 约 4–8s/step | 远程评测的延迟是架构变量；长 chunk/世界模型在接触段更吃亏；评测协议本身会改变排名 |
| **DC-Ada**（arXiv 2604.03905） | 异构多机器人团队的 sensing/range/FOV/故障差异会让冻结策略显著退化；用 per-robot observation transform 适配固定推理接口 | “每机器人一个小变换”比“每机器人一个模型”更符合单模型规则；端口指纹就是这种小变换 |
| **RLS 无标定视觉伺服**（UR 2025, DOI 10.1109/UR65550.2025.11078118） | RLS 在线估计图像雅可比可微调，但在大初值偏差/坏初值时，稳态精度和收敛常与静态标定相当甚至更差 | 不能“从零 RLS”；必须用标称 K/运动学初始化、低维参数化、正则化和置信度门控 |

**综合判断**：多机评测的第一阶变量不是“模型架构”，而是**每端口的几何/动作系/延迟**；第二阶才是最后 3 厘米的接触闭环。LLM 的价值不在在线推理，而在**离线把任务知识编译成可执行的阶段/特征/恢复规则**。

## 2. 诊断：每端口三个未知，叠加一个被榜单掩盖的方差

### 2.1 三个未知

把一次 `get_action` 拆开，策略真正缺的是三组量：

1. **几何未知**：头部内参/外参、腕部手眼、桌面平面、物体尺度。头部 `fx` 跨任务差 1.6 倍；腕部 K 稳，但手眼变换和安装偏差未知。
2. **动作系未知**：EE 的 TCP 偏置、`pivot` 7 维语义、`joint`/`ee` 的符号与顺序、gripper 的 0–1 映射。WLA 54D 与挑战赛 21D 不是天然对齐的。
3. **时序未知**：evaluator 的真实控制频率、RTT、JPEG 编解码、推理排队、chunk 执行抖动。`T_fb ≈ H_c/f_c + τ`；如果 `f_c=10Hz`，5 步 chunk 的反馈周期就是 500ms，不是 167ms。

### 2.2 误差传播：为什么“先标定”比“再训模型”便宜

以腕部单目 IBVS 为例，横向误差 `e` 与深度 `Z`、焦距 `f` 的关系近似：

```math
\Delta X \approx \frac{Z}{f}\,\Delta u,\qquad
\frac{\partial \Delta X}{\partial f}=-\frac{Z\,\Delta u}{f^2}.
```

若 `Z=0.3m`、`f=435px`、`Δu=10px`，则 `ΔX≈6.9mm`；若 `f` 有 5% 误差，横向就有约 0.35mm 的系统偏差。头部 `f` 从 186 到 296（差 59%），同一像素偏差对应的米制误差差近 1.6 倍。**在不知道当前端口 `f` 的情况下，用固定米制增益做伺服，本身就会引入端口相关偏差。**

动作系更致命：TCP 偏置 1cm，在插入任务里就是“永远差 1cm”；`pivot` 符号错，机器人可能不动或反向。**这些不是模型容量能补的，必须先标定/适配。**

### 2.3 排行榜的方差：9.2pp 的头尾差距，可能小于端口差异

- 320 trials 下，`p≈0.25` 的单次标准误约 **2.42pp**；`p≈0.5` 时约 **2.80pp**。
- 公开榜单头尾只差 **9.2pp**；真实多机评测里，不同端口/测试者/初始条件造成的差异可以轻松达到几十 pp（RoboChallenge 甚至报告 0–100%）。
- 因此，**“换一个更强的模型”与“把当前模型在每个端口上标定好”可能是同一量级的收益；后者更便宜、更可控、更符合单模型规则。**
- 合成榜单的任务排名不能用来分配工程；真正的任务优先级要来自单任务不计分通道的配对 A/B。

### 2.4 LLM 的位置：离线编译器，不是在线大脑

LLM 适合做三件事：

1. 把 32 条任务说明、演示统计、失败模式编译成**结构化任务卡**：阶段、关键特征、成功谓词、恢复动作、可标定性、泛化轴注意事项。
2. 把任务卡编译成**离线评测 rubric**，用于单任务通道的失败分诊和私有 mini-board。
3. 把公开模型家族的技术路线/外部文献整理成**假设清单**，帮助人类做剪枝。

LLM 不适合做三件事：

1. 在线直接输出关节/EE 动作（延迟、幻觉、安全、单模型合规）。
2. 在线做第二个 VLM 感知器（违反单模型精神，且增加 RTT）。
3. 在线做安全关键决策（接触/碰撞/急停必须由确定性控制器和限幅兜底）。

**合规写法**：LLM 只在离线生成静态 JSON；提交物里没有 LLM 权重；在线策略只读 JSON；如果组织方严格解释“同一模型”，就由人类编辑/审核任务卡，LLM 只做草稿工具。任务卡不是模型，是配置。

## 3. 方法：FLEET-PORTRAIT

### 3.1 总架构

```text
                    ┌─────────────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1)         │
                    │  scored 32×10 / unscored single-task debug  │
                    └──────────────┬──────────────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
        ┌──────────────────────────────────────────────────────────┐
        │  Per-port PolicyService (CPU, independent, reset-safe)   │
        │  ├─ PORTRAIT: head pose / wrist K / hand-eye / plane / τ  │
        │  ├─ TASK-CARD lookup: phase / feature / predicate / rec.  │
        │  ├─ goal retrieval: demo keyframes + relative pose        │
        │  ├─ FLEET-UVS: low-dim online image Jacobian + gating     │
        │  ├─ plan cache: 30-step VLA plan (async)                  │
        │  └─ action adapter: WLA 54D → challenge 21D + safety      │
        └──────────────┬───────────────────────────────────────────┘
                       │ async, batched, per-port queue
                       ▼
        ┌──────────────────────────────────────────────────────────┐
        │  Shared VLA server (GPU)                                 │
        │  UnifoLM-WLA-1.0 / VLA-0, 30-step plan                   │
        └──────────────────────────────────────────────────────────┘
```

- **唯一学习模型**：VLA（官方 WLA 微调 action head）。
- **确定性控制器**：端口指纹 + 视觉伺服 + 动作适配 + 安全限幅；无学习权重；不违反单模型。
- **数据资产**：33k 成功演示 → 任务卡统计、目标图、相对位姿、相机参数分布；不是第二个模型，是检索/配置。
- **数字孪生**：只做标定/压力测试，不训练策略。

### 3.2 每端口指纹（PORTRAIT）

每个端口维护一个轻量 JSON（示例）：

```json
{
  "port": 8765,
  "robot_id_hint": "G1_Dex1",
  "head": {
    "pose_model": "linear_waist_to_d435",
    "coef": [[...], ...],
    "residual_mm": 0.3,
    "confidence": 0.0
  },
  "wrist": {
    "K_nominal": [[433.1, 0, 320.0], [0, 433.1, 240.0], [0, 0, 1]],
    "dist_nominal": [...],
    "T_ee_cam": null,
    "handeye_confidence": 0.0
  },
  "table_plane": {"n": [0, 0, 1], "d": 0.0, "confidence": 0.0},
  "action": {
    "ee_frame": "base",
    "tcp_offset": [0, 0, 0],
    "pivot_map": "linear_fit_v1",
    "gripper_scale": [0.0, 1.0]
  },
  "timing": {"f_c_hz": 30.0, "rtt_ms_p50": 0.0, "rtt_ms_p95": 0.0, "n_calls": 0},
  "task_state": "cleared_on_reset"
}
```

关键设计：

- **端口级持久，任务级清空**：`reset()` 只清任务状态、目标、相位、缓存；不清头部姿态/腕部手眼/延迟统计。这样第 2 个任务开始，端口已经“更熟”。
- **置信度驱动**：每个量都有 `confidence`；低于阈值就回退到标称值/纯 VLA，不强行伺服。
- **不跨端口共享任务观测**：可以共享 VLA 权重和总体先验；不共享某个端口的任务图像/成功轨迹。多机隔离是硬约束。
- **可选机器人级共享**：如果确认同一机器人对应多个端口，可共享**机器人级**指纹（相机型号、TCP、延迟），但不共享任务级状态；默认关闭，避免误判。

#### 3.2.1 头部姿态：从 `lower_body` 到 `T_base_d435`

离线：用 32 个数据集的 `(waist_state_joint, state_d435)` 拟合线性/二次模型；按任务/会话分组做留出验证。

在线：

```text
q_waist = obs.lower_body[-3:]
T_base_d435_hat = f(q_waist)          # 线性优先；二次仅在 G1 显示线性不足时启用
```

用途：

- 把头部图像中的目标方向/桌面平面变到 base 系；
- 为 PBVS 提供相机姿态；
- 为“目标是否在视野内/是否被夹爪挡住”提供几何检查；
- **不**直接用头部像素做米制深度；头部尺度用腕部/演示先验补。

风险：头部可能还有 neck/torso 自由度，`lower_body` 只给腰 3 关节；全量验证若残差 > 5mm/5mrad，就加一个视觉更新（用桌面平面/已知物体尺度）或降级为“只用姿态、不用平移”。

#### 3.2.2 腕部：标称 K + 在线手眼

离线：取 32 个数据集腕部彩色 K 的中位数作为 `K_nominal`；记录 `image_resize` 对应的缩放；把畸变模型固定为 `inverse_brown_conrady`。

在线：

- 若 `image_resize` 改变图像尺寸，按 `s = W_resize/W_orig` 缩放 `fx, fy, cx, cy`；这是最容易错的工程细节。
- 手眼 `T_ee_cam` 用两种方式初始化：
  1. **演示先验**：从数据集的 EE 位姿 + 腕部图像特征，离线标一个平均手眼；
  2. **在线低维修正**：只估计 3 个平移 + 1 个安装角（或 6D 但强正则），用任务运动中的 `(ΔEE, Δ特征)` 做 RLS/Broyden 更新。
- 置信度低时，不用腕部米制伺服，只用 2D 特征对齐/纯 VLA。

#### 3.2.3 桌面平面与动作系

- 桌面平面：用头部姿态 + 演示先验初始化；用腕部/头部看到的桌面点做鲁棒平面拟合；只用于把目标高度约束到桌面附近，不用于精确接触力。
- TCP 偏置：用数据集 `ee_pose_gripper_base` 与 WLA 的 EE 定义拟合；用 `example_env.py` 回放验证。
- `pivot`：从数据集 `action.pivot` 与 `base_command/waist_action_joint/action_torso` 拟合低维映射；先在仿真/单任务通道验证符号和顺序；保留“零 pivot + 纯 EE”回退。
- gripper：用数据集分布拟合 0–1 映射；保留限幅和速率限制。

#### 3.2.4 延迟

- 每次 `get_action` 记录 `t_recv, t_send`，用相邻调用间隔估计 `f_c`；用 `t_send - t_recv` 加服务端时间戳估计 RTT 下界。
- 维护 p50/p95；`H_c` 在提交前扫 `{3,5,8}`，但 `action_chunk_size` 是固定元数据，不能在线改；所以选一个保守值（建议 5），并用预测/降增益适配延迟。
- 如果实测 `f_c < 15Hz` 或 p95 RTT > 200ms，关掉高频伺服，退回 8–10 步 chunk + 纯 VLA/PBVS。

### 3.3 任务即标定（TASK-AS-CALIBRATION）

不做“先让机器人做一套标定动作”。标定样本来自任务本身的正常运动：

```text
每个执行块：
  a_ff = VLA plan[t:t+H_c]
  obs  = 当前四路 RGB + 本体
  特征 = 任务卡指定 ROI 内的目标/夹爪/接触点
  记录 (ΔEE_cmd, Δ特征)
  若运动激励足够（特征位移 > 阈值，且不在接触段）：
      更新手眼/图像雅可比的后验
  若在接触段或特征不可靠：
      冻结更新，只用先验 + 保守伺服
```

“可标定性”由任务卡标记：

- **高**：接近、对位、抓取、放置、插拔前的自由空间运动；特征位移大，适合估手眼/雅可比。
- **中**：叠放、挂杯、拉拉链；有接触，但仍有横向/旋转激励。
- **低**：纯按压、纯拉、纯倒、接触后微调；几乎无自由空间激励，不更新，只用先验。

**冷启动策略**：

1. 第一个任务若是“高可标定”，先积累 1–2 个执行块的样本，再开伺服；
2. 第一个任务若是“低可标定”，用标称 K + 演示先验 + 纯 VLA，等下一个任务再标；
3. 每个端口独立；不假设端口顺序；端口指纹跨 episode 保留；
4. 若 evaluator 在任务间重启服务，指纹丢失，回退到标称值（无损）。

### 3.4 FLEET-UVS：低维、正则化、带门控的在线图像雅可比

经典 IBVS：

```math
\dot{s} = L_s\,v,\qquad
v = -\lambda\,\widehat{L_s^{+}}\,(s-s^{*}).
```

`L_s` 依赖 `f, Z, 像素坐标`；多端口下 `f,Z` 未知。FLEET-UVS 不估计完整 `L_s`，而是估计**低维残差**：

```math
\widehat{L_s} = L_s^{0}(K_{\mathrm{nom}}, Z_{\mathrm{prior}})\;\bigl(I + \Delta L\bigr),
```

其中 `ΔL` 只允许：

- 2 个横向尺度（x/y 增益）；
- 1 个旋转-平移耦合项；
- 1 个深度尺度（整体增益）；
- 可选 1 个安装角。

即 **4–5 个参数**，不是 2×6 的完整雅可比。用正则化 RLS/Broyden：

```math
\Delta L_{k+1} = \arg\min_{\Delta L}
\sum_{i=1}^{k}\lambda^{k-i}
\bigl\| \Delta s_i - L_s^{0}\,\Delta L\,\Delta \xi_i \bigr\|^2
+ \mu\|\Delta L\|_F^2,
```

- `λ` 忘记因子 0.95–0.99；
- `μ` 强正则，把 `ΔL` 拉向 0；
- 只在“非接触 + 特征可靠 + 激励足够”时更新；
- 更新后做**稳定性检查**：`L_s^+` 的条件数、增益上下界、单步修正上限（1cm/0.05rad）；
- 连续 N 次误差不降/发散，冻结并回退到标称雅可比/纯 VLA。

**为什么不用完整 RLS**：UR 2025 的结果明确说，RLS UVS 在大初值偏差/坏初值时可能不如静态标定。我们的做法是“标称模型 + 低维残差”，把 RLS 限制在它擅长的局部微调，而不是让它从零学整个雅可比。这是与“纯无标定 UVS”的关键差异。

**执行层**：

```text
a_ff = VLA plan[t:t+H_c]              # H_c = 5
e    = servo_error(obs, goal, card)    # 目标来自演示相对位姿 + 任务卡特征
Δ    = clip(K_p e + K_d ė, ±1cm, ±0.05rad)
a_cmd = a_ff ∘ exp(Δ)
```

- 远距离：PBVS（头部姿态 + 目标相对位姿），稳定、全局；
- 近距离：FLEET-UVS/IBVS（腕部特征），抗标定误差；
- 接触段：法向缩幅/低通，切向保留；用第 11 轮的 `d_t, n_t, r_static, r_grasp` 做门控；
- 人为干扰：检测到“动作解释不了的残差” → 停 → 重定位 → 重规划（第 11 轮 GEO-RESIDUAL 的恢复逻辑）。

### 3.5 TASK-CARD：LLM 离线编译，在线只读 JSON

任务卡 schema（示例，不是最终字段）：

```json
{
  "task_id": "HangCup",
  "language_aliases": ["hang the cup", "把杯子挂到杯架上"],
  "stages": [
    {
      "name": "approach",
      "phase": "free_space",
      "feature": "cup_rim + rack_hook",
      "success": "cup_rim within 2cm of hook",
      "servo": "pbvs_then_ibvs",
      "calibration_friendly": 0.9,
      "recovery": ["retreat_2cm", "re_localize", "re_approach"]
    },
    {
      "name": "hang",
      "phase": "contact",
      "feature": "hook_contact + gripper_orientation",
      "success": "cup hangs without support for 1s",
      "servo": "normal_reduced",
      "calibration_friendly": 0.2,
      "recovery": ["lift_1cm", "rotate_5deg", "retry"]
    }
  ],
  "generalization_notes": {
    "position": "re-localize target; relative goal",
    "distractor": "ROI only; ignore background",
    "background": "do not use global color",
    "unseen_object": "VLA semantics; keep receptacle geometry",
    "human": "detect scene change; stop; re-localize"
  },
  "safety": ["max_speed", "max_force_proxy", "max_retries"],
  "source": ["official_instruction", "demo_stats", "human_review"]
}
```

LLM 编译流程：

1. 输入：32 条官方任务说明（中/英）、每任务 20–50 条演示的统计（时长、步骤、关键帧）、失败模式先验、API 约束。
2. 输出：候选任务卡 JSON；每个字段带 `source` 和 `confidence`。
3. 人工/规则校验：schema 校验、动作合法性、成功谓词可观测性、恢复动作安全性。
4. 冻结：只保留通过校验的字段；不确定的字段写 `null`，在线回退到通用卡。
5. 在线：用 `observation.language` 做精确/关键词匹配；匹配不到时用 VLA 自己的 text encoder 算 32 张卡的相似度（同 checkpoint，不是第二个模型）；再不行用通用卡。

**任务卡不做什么**：

- 不输出低层动作；
- 不做在线推理；
- 不替代 VLA 的语义理解；
- 不把“阶段”硬编码成固定轨迹；阶段是**观测/特征/门控**，不是时间表。

### 3.6 ROBUST-SUBMIT：把正式评测当带方差的投资组合

- **私有 mini-board**：从 32 任务分层选 8 个（2 Easy / 3 Medium / 3 Hard，覆盖插入、挂、叠、拉链、变形、人为干扰），每个 5 次配对 A/B；用单任务不计分通道跑。
- **配对设计**：同一初始条件、同一端口、A/B 交替；记录成功、步骤分、p99 延迟、恢复次数；用配对差值的 bootstrap 95% 下界，而不是只看均值。
- **选择规则**：`LCB(ΔS) > 0` 且 `CVaR_20%(task success)` 不下降才升级；否则保留基线。`S` 是 32 任务平均成功率；`CVaR_20%` 防止“平均涨、尾部崩”。
- **提交节奏**：若允许多次提交（需邮件确认），先交安全基线锁“更早提交”的 tie-break，再交通过门的版本；若只允许一次，先用单任务通道把版本打磨稳定，再交最终版。
- **不追合成榜单**：公开榜单的任务排名是脚本生成的；只把它当“预览上限/赛事信号”，不用它决定 32 个任务的工程预算。

### 3.7 与第 10/11/12 轮的关系

**保留**：

- FACT-VLA 的相位化 BC、CAC 柔顺执行、EGP 证据门控；
- GEO-RESIDUAL 的动作条件化残差、米制表面距离、编辑检测；
- CHUNK-SERVO 的 30 步规划 + 5 步执行、相对目标、接触段法向缩幅；
- 官方 WLA 基座、33k 演示、官方 rubric、单任务通道。

**升级**：

- 从“假设几何已知”升级为“每端口在线标定”；
- 从“全局 IBVS”升级为“标称雅可比 + 低维残差 + 置信度门控”；
- 从“手工任务规则”升级为“LLM 离线任务卡 + 在线静态查表”；
- 从“榜单任务排名”升级为“私有 mini-board + 配对 LCB”；
- 从“一个端口”升级为“N 端口独立指纹 + 共享 VLA”。

**剪枝**：

- 不做腕部棋盘格标定（数据里已有标称 K；真正未知的是手眼，可在线估）；
- 不做完整 RLS 从零学雅可比（UR 2025 已示警；用低维残差）；
- 不做在线第二个 LLM/VLM（单模型 + 延迟 + 幻觉）；
- 不做头部深度硬依赖（线上无 depth/视差）；
- 不做从零训 VLA/World Model（官方 WLA 已做完，算力不划算）；
- 不做完整 sim-to-real 策略训练（只做控制器风洞）；
- 不做 6D 物体位姿网络（透明/变形不可靠；用相对目标 + 局部对齐）；
- 不做力/触觉闭环（API 没有）；
- 不把预览榜单的任务排名当难度表（已证伪）；
- 不做 32 个任务各一个策略（规则禁止，且不泛化）。

**明确不建议继续投**：从零训通用 VLA/World Model、完整 sim-to-real 策略训练、30Hz 广域网视觉伺服、逐任务学习策略、6D 物体位姿网络、力/触觉闭环（API 没有）、在线第二个大模型。这些方向要么已被官方 WLA 覆盖，要么被规则/接口/延迟/数据限制，边际收益低于“每端口标定 + 执行层闭环”。

## 4. 创新点清单（含动机/差异/可行性/资源/步骤/风险）

### I1. FLEET-PORTRAIT：每端口被动指纹

- **动机**：多机评测下，N 个端口的头部内参/外参、腕部手眼、TCP、桌面平面、延迟都未知；真实机器人硬件偏移可让 VLA 从近 100% 掉到近 0%（Self-Adaptive VLA）；DC-Ada 证明 per-robot observation transform 是异构团队的实用适配层。
- **与现有方案差异**：不是“每台机器人一个模型”，也不是“离线一次性标定”；是每端口一组轻量、低维、带置信度的确定性参数，跨 episode 保留、任务态隔离。与 CHUNK-SERVO 相比，补上了“几何未知”这个前提。
- **技术可行性**：头部姿态试点 R²>0.999；腕部 K 跨任务稳定；手眼/平面/延迟都有成熟估计方法；全部 CPU 轻量，不抢 GPU。
- **所需资源**：33k 演示元数据；1 台 CPU；四路 RGB + 本体；不需要额外传感器/标定板；1–2 周工程。
- **落地步骤**：G0 数据审计 → G1 头部姿态全量拟合 → G2 腕部手眼/平面估计 → G3 仿真验证 → G4 单任务通道 → G5 多端口干跑。
- **风险**：头部还有 neck/torso 自由度；手眼激励不足；端口重启丢指纹；跨端口误共享。缓解：置信度门控、标称回退、默认不共享、持久化存储。
- **结论**：**保留，作为本轮第一核心。**

### I2. TASK-AS-CALIBRATION + FLEET-UVS：用任务运动标定，用低维残差伺服

- **动机**：额外标定动作会浪费 180s/任务，且可能改变场景；任务本身的接近/对位/抓取就是天然激励。完整 RLS UVS 在坏初值下可能不如静态标定（UR 2025），所以需要“标称 + 低维残差”。
- **与现有方案差异**：不是纯 IBVS/PBVS，也不是完整无标定 RLS；是“标称雅可比 + 4–5 维残差 + 正则化 + 置信度门控 + 接触段冻结”。任务卡告诉它“现在是否适合标定”。
- **技术可行性**：腕部 K 已知；EE 位姿可得；低维参数化显著降低样本复杂度；失败可回退到纯 VLA/PBVS。
- **所需资源**：33k 演示；CPU；1×24GB GPU（VLA 微调）；仿真环境；2–3 周。
- **落地步骤**：G2 离线手眼/雅可比拟合 → G3 仿真扫增益/延迟 → G4 单任务 A/B → G5 多端口/人为干扰 → G6 消融（低维 vs 完整 RLS vs 静态）。
- **风险**：接触段激励不足；透明/反光特征丢失；RLS 发散；修正与 VLA 前馈冲突。缓解：只在自由空间更新、强正则、单步限幅、连续失败冻结、接触段法向缩幅。
- **结论**：**保留，作为本轮第二核心；先做低维残差，不直接上完整 RLS。**

### I3. TASK-CARD：LLM 离线编译 32 张任务卡

- **动机**：32 个任务、长程、接触阶段多；语言是唯一任务 ID；单模型规则禁止在线第二个学习模型。LLM 可以把任务说明/演示统计/失败模式编译成结构化知识，降低手工规则成本。
- **与现有方案差异**：不是“LLM 在线规划/输出动作”，也不是“VLA 端到端包办一切”；是离线编译器 + 在线静态 JSON + 同 checkpoint text encoder 匹配。任务卡是配置，不是模型。
- **技术可行性**：32 条任务说明 + 33k 演示统计足够；JSON schema 可校验；人工审核可控；LLM API 便宜；不增加在线延迟。
- **所需资源**：32 条官方说明；每任务 20–50 条演示统计；LLM API；1–2 人日；人工审核 1 天。
- **落地步骤**：抽取说明/语言别名 → 采样演示统计 → LLM 生成候选卡 → schema/安全/可观测性校验 → 人工冻结 → 在线查表 + 通用卡回退。
- **风险**：LLM 幻觉阶段/成功谓词；语言别名不匹配；任务卡过拟合演示；组织方对“模型”解释严格。缓解：字段带 source/confidence、不确定写 null、人工审核、纯配置提交、必要时人类重写。
- **结论**：**保留，作为使能技术；不作为核心卖点。**

### I4. ROBUST-SUBMIT：排行榜稳健评测

- **动机**：公开榜单是合成的；真实评测方差大（RoboChallenge 0–100%）；320 trials 的 SE≈2.4pp；头尾 9.2pp 可能小于端口差异。必须用配对/分层/置信区间，而不是追合成任务排名。
- **与现有方案差异**：不是“多刷榜单/调任务权重”；是私有 mini-board + 同条件配对 A/B + bootstrap LCB + CVaR + 先交安全基线锁 tie-break。
- **技术可行性**：单任务不计分通道可用；bootstrap/配对统计成熟；8 任务 ×5 次 A/B 在预算内；可离线复算。
- **所需资源**：单任务通道时段；8 个代表任务；1 名统计/评测负责人；1 周。
- **落地步骤**：分层选 8 任务 → 定义 A/B 协议 → 跑配对 → 估 LCB/CVaR → 选 checkpoint → 正式提交 → 复盘。
- **风险**：debug 通道分布与正式评测不同；样本小；提交次数限制；私有 mini-board 过拟合。缓解：分层覆盖、重复测量、保留 holdout 任务、邮件确认提交规则。
- **结论**：**保留，作为竞赛策略；不把合成榜单当优化目标。**

### I5. FLEET-AUG：按真实相机参数分布做训练增强（可选）

- **动机**：头部 `fx` 跨任务 186–296、基线 47–65mm；VLA 可能过拟合训练端口的几何。用真实分布做增强，比任意随机裁剪更贴近多机评测。
- **与现有方案差异**：不是“更多随机增强”；是从 32 个数据集的 `camera_params` 采样真实 `f/基线/分辨率`，做几何一致的图像变换/重投影增强。
- **技术可行性**：参数已在元数据里；action head 微调 24GB 可跑；增强不影响推理。
- **所需资源**：33k 演示；1×24GB GPU；1–2 周；需要小心不要破坏动作标签。
- **落地步骤**：统计参数分布 → 实现几何一致增强 → 小规模微调 → 留任务验证 → 与不增强对比。
- **风险**：增强过强导致语义失真；动作标签与图像变换不一致；算力/时间不够。缓解：只在 action-head 微调阶段用、限制变换范围、留任务验证。
- **结论**：**可选，放在 G7 之后；不是本轮核心。**

### I6. PIVOT-SEMANTICS：WLA 54D → 挑战赛 21D 的动作适配（工程必需）

- **动机**：WLA 54D 与挑战赛 21D 不是天然对齐；`pivot` 7 维语义、TCP 偏置、gripper 映射错一个就整体失败。
- **与现有方案差异**：不是“直接端到端映射”；是用数据集 `action.pivot/base_command/action_torso/waist` 拟合低维映射，用 `example_env.py`/单任务通道回放验证，保留零 pivot 回退。
- **技术可行性**：数据里有对应字段；映射低维；可离线回放；可单任务验证。
- **所需资源**：33k 演示；CPU；1 周；官方 example。
- **落地步骤**：字段分布审计 → 拟合 pivot/TCP/gripper → 离线回放 → 仿真/单任务验证 → 保留回退。
- **风险**：语义仍不完全一致；不同端口机器人差异；动作帧/符号错。缓解：先验证再上线、限幅、零 pivot 回退、单任务通道。
- **结论**：**必需，但不作为创新点卖；它是所有方案的地基。**

## 6. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定为第二个模型 | 在线只有 VLA 一个学习模型；任务卡是静态 JSON；伺服/指纹无学习权重；提交材料写清楚 |
| LLM 任务卡被当模型 | 合规争议 | LLM 仅离线草稿；提交物无 LLM 权重；必要时人类重写；任务卡可审计 |
| 头部姿态模型跨任务失效 | PBVS 偏差 | G1 全量验证；残差大时只用姿态/加视觉更新/回退腕部 |
| 手眼激励不足 | FLEET-UVS 不收敛 | 任务卡标记可标定性；低维残差；置信度门控；回退标称/纯 VLA |
| RLS 发散 | 动作抖动/超调 | 强正则、忘记因子、单步限幅、连续失败冻结、完整 RLS 只做对照 |
| 透明/反光/变形 | 特征丢失 | 只对刚体任务启用；腕部 2D + 夹爪滞止兜底；任务卡标记不可用 |
| 端口重启/指纹丢失 | 冷启动变慢 | 持久化端口指纹；标称回退；不假设端口顺序 |
| 跨端口任务态泄漏 | 违反隔离 | 默认不共享任务观测；指纹只含机器人级参数；代码审计 |
| 远程 RTT 高 | 伺服带宽不足 | 5 步 chunk；RTT 测量；预测/降增益；p95 超标回退 8–10 步 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap LCB、CVaR、重复实验；320 trials SE≈2.4pp |
| 合成榜单误导 | 工程投错任务 | 只当预览上限；私有 mini-board 决定优先级；不追任务排名 |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |
| 安全 | 回撤/重抓碰撞 | 限速/限幅/最大重试；编辑检测即停；零 pivot 回退 |

## 7. 一句话押注

**在多机评测里，先别急着换更大的 VLA：把每个端口当成一台未标定的机器人，用任务本身的运动在线恢复头部姿态、腕部手眼、桌面平面、动作系偏置和延迟；用 LLM 离线编译的 32 张任务卡决定“现在该信哪个特征、该不该更新、失败怎么退”；用低维正则化的 FLEET-UVS 在最后 1–2 cm 闭环；用配对 LCB/CVaR 而不是合成榜单决定提交——在不违反单模型规则的前提下，把“N 个未知端口”变成“N 个已标定端口”。**

# 第 13 轮产物 · FLEET-PORTRAIT 技术报告

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「FLEET-PORTRAIT」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是修正 CHUNK-SERVO 的“单一已标定端口”前提，把每端口在线标定、LLM 离线任务卡、排行榜稳健评测接到控制环。

## 0. 结论与边界

### 0.1 一句话结论

**多机评测的第一阶变量是每端口的几何/动作系/延迟，不是模型架构。** 先用任务本身的正常运动被动恢复头部姿态、腕部手眼、桌面平面、TCP/`pivot` 偏置和延迟；再用 LLM 离线编译的 32 张任务卡决定阶段/特征/恢复/可标定性；最后用低维正则化的 FLEET-UVS 在自由空间做 1–2 cm 修正，接触段法向缩幅。公开榜单是合成预览，只能当上限信号；正式评测用配对 A/B、bootstrap LCB、CVaR 选 checkpoint。

### 0.2 证据等级

- **A**：官方页面/规则/README/API、HF 数据集 `meta/info.json`、官方 WLA 文档、我们直接下载的 JSON 统计。
- **B**：公开论文/排行榜 JSON 的回归与相关性分析、外部 benchmark 的定性结论。
- **C**：我们的设计假设/工程推断；必须用 G0–G9 实验门验证。

### 0.3 本轮不做什么

- 不从零训 6B/14B VLA 或世界模型；用官方 WLA Base 做 action-head 微调。
- 不做完整 sim-to-real 策略训练；数字孪生只做标定/调参/压测。
- 不做在线第二个 LLM/VLM；LLM 只在离线编译任务卡。
- 不做头部深度硬依赖；线上只有 RGB，没有 depth/双目视差。
- 不做腕部棋盘格标定；数据里已有标称 K，真正未知的是手眼。
- 不做完整 RLS 从零学图像雅可比；用标称模型 + 低维残差。
- 不做 6D 物体位姿网络/力触觉闭环；API 没有力/触觉，透明/变形不可靠。
- 不把公开榜单的任务排名当难度表；它是脚本生成的预览。

## 1. 事实核对

### 1.1 比赛规则（A）

来源：官方参赛手册（飞书，中文/英文两版；`r.jina.ai` 抓取），2026-10-28 抓取、2026-10-31 复核。

- 赛事：宇树 **UniBot 世界挑战赛**，G1 + Dex1，32 项桌面任务，通才模型赛道。
- 模型：所有任务须基于**同一模型**完成；不得混合多个模型；模型类型不限（World Model、VLA 均可）。
- 评测：32 任务 ×10 次独立运行；5 类泛化各 2 次（位置、干扰物、桌面背景、未见物品、人为干扰）。
- 时间：单次真机执行上限 **180 s**。
- 排名：先看 32 任务总平均成功率；相同看总平均步骤分；再相同看更早提交。
- 多机：评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立交互；`reset()` 状态必须隔离。
- 测试：另有**不计分的单任务测试通道**；官网个人页有「提交测试 / 预约评测时段」，但大量内容显示「即将发布」。

**未确认**：N 的具体值；是否允许多次计分提交/提交次数上限；评测端真实控制频率；RTT 分布；`pivot` 7 维精确语义；挑战赛 32 任务是否都包含在 WLA 64 任务训练集中；死区/超时/重试的具体判定。凡涉及这些的结论都标 C，必须实测/邮件确认。

### 1.2 提交 API（A）

来源：`unitreerobotics/unibot_submission` README（当前 v2，commit `edd0a1c986`，2026-08-21）与 `example/`。

- 观测：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB 480×640；双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str`。
- 动作：`joint` 或 `ee` 互斥；`ee` 为 **2×6 EE + 2×1 gripper + 7 pivot = 21 维**；`joint` 通道维度以 README 为准。
- Metadata：`control_space`、`obs_delta_indices`、`image_resize`、`action_chunk_size`、`token`；旧版 `data_keys`/`obs_chunk_size` 已过时。
- `obs_delta_indices` 决定传哪些键、堆叠几帧；`image_resize` 可缩放；`meta.token` 每次 `get_action` 都要带。
- `action_chunk_size` 固定；evaluator 按 leading time-axis 顺序执行；index 0 先执行；chunk 内没有新观测、没有打断机制。
- 无 depth、camera_info、force/torque、tactile。
- 评测端逐调用记录延迟、波动和动作统计规律，作为结果可信度的一部分。

**关键推论**：

```math
T_{\mathrm{fb}} \approx \frac{H_c}{f_c} + \tau
```

`H_c=30, f_c=30Hz, τ=50ms` → 约 **1050ms** 开环；`H_c=5, f_c=30Hz, τ=50ms` → 约 **217ms**。如果真实 `f_c=10Hz`，`H_c=5` 也有 500ms+τ。**`H_c` 是控制参数，不是拍脑袋的推理参数；但它是固定元数据，提交前必须扫。**

## 2. 问题形式化

### 2.1 评分与不确定性

总分：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

320 trials 下，若 `p≈0.25`：

```math
\mathrm{SE}(S)\approx \sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

`p≈0.5` 时约 **0.0280**。配对 A/B 的方差取决于任务内相关；若同一初始条件 A/B 成功高度相关，配对差值方差可显著降低。报告必须给配对差值的 bootstrap 置信区间，而不是只报两个平均值。

人为干扰轴：

```math
\Delta S_{\mathrm{human}} = \frac{2}{10}\,\Delta p_h = 0.2\,\Delta p_h.
```

即 human 轴 +10pp → 全局 +2pp（每任务 10 次里 2 次 human；32 任务平均后仍是 0.2 倍）。

**排名不确定性**：公开榜单头尾 9.2pp，小于/接近端口差异；不要用合成榜单的任务排名做工程预算。私有 mini-board 用 8 任务 ×5 次配对，配对差值的 SE 取决于任务内相关，必须 bootstrap。

### 2.2 每端口状态模型

对端口 `i`，定义：

```math
P_i = \bigl(K_h, T_{b h}, K_w, T_{e c}, \Pi, b_a, \tau_i\bigr),
```

- `K_h`：头部内参（未知，跨任务 186–296px）；
- `T_{b h}`：头部相机在 base 系的位姿（可由 `lower_body` 恢复）；
- `K_w`：腕部彩色内参（标称 433–437px；`image_resize` 缩放）；
- `T_{e c}`：腕部相机到 EE 的手眼（未知，在线低维修正）；
- `\Pi`：桌面平面；
- `b_a`：动作系偏置/TCP/`pivot` 映射/gripper 映射；
- `\tau_i`：该端口的延迟/抖动统计。

每个量带置信度 `c ∈ [0,1]`。在线只在高置信度时使用；低置信度回退到标称/纯 VLA。

**端口级持久，任务级清空**：

```text
Portrait_i:  跨 episode 保留（头部姿态、腕部手眼、平面、延迟）
TaskState_i: 每次 reset() 清空（目标、相位、缓存、重试计数）
```

**隔离**：不跨端口共享任务观测/成功轨迹；默认不共享端口指纹。可选的“机器人级共享”只共享相机型号/TCP/延迟先验，且必须确认端口与机器人对应关系。

### 2.3 头部姿态模型

离线：

```math
T_{b h} = f(q_w) + \varepsilon,\qquad
f(q_w) = A\,[q_w,1]^{T}\ \text{或}\ A\,[q_w,q_w^2,1]^{T}.
```

在线：

```text

T_bh_hat = f(q_waist)
```

- 不随机抽帧，避免相邻帧泄漏。

### 2.4 腕部手眼与 FLEET-UVS

腕部相机模型：

```math
s = \pi(K_w\,T_{c e}\,T_{b e}^{-1}\,X_b),
```

其中 `T_{c e}` 是 EE 到相机（手眼），`T_{b e}` 是 EE 在 base 系的位姿。`K_w` 有标称；`T_{c e}` 未知/有安装偏差。

经典 IBVS：

```math
\dot{s} = L_s\,v,\qquad
v = -\lambda\,\widehat{L_s^{+}}\,(s-s^{*}).
```

`L_s` 依赖 `f, Z, 像素坐标`。FLEET-UVS 不估计完整 `L_s`，而是：

```math
\widehat{L_s} = L_s^{0}(K_{\mathrm{nom}}, Z_{\mathrm{prior}})\;\bigl(I + \Delta L\bigr),
```

`ΔL` 只允许 4–5 个参数：

- 2 个横向尺度（x/y 增益）；
- 1 个旋转-平移耦合；
- 1 个深度尺度/整体增益；
- 可选 1 个安装角。

正则化 RLS/Broyden：

```math
\Delta L_{k+1} = \arg\min_{\Delta L}
\sum_{i=1}^{k}\lambda^{k-i}
\bigl\| \Delta s_i - L_s^{0}\,\Delta L\,\Delta \xi_i \bigr\|^2
+ \mu\|\Delta L\|_F^2.
```

- `λ` 忘记因子 0.95–0.99；
- `μ` 强正则，把 `ΔL` 拉向 0；
- 只在“非接触 + 特征可靠 + 激励足够”时更新；
- 更新后检查 `L_s^+` 条件数、增益上下界、单步修正上限（1cm/0.05rad）；
- 连续 N 次误差不降/发散 → 冻结，回退标称/纯 VLA。

**为什么低维**：UR 2025 表明完整 RLS UVS 在大初值偏差/坏初值时可能不如静态标定；我们只用 RLS 做局部微调，把“可辨识性”限制在 4–5 维，降低样本复杂度和发散风险。

**可辨识性条件**：

- 特征位移足够大（自由空间接近/对位）；
- 激励方向不全共线（至少两个方向的运动）；
- 特征不在接触/遮挡/透明/反光失效区；
- `ΔEE` 与 `Δs` 的时间对齐（考虑 RTT/chunk 延迟）。

不满足就冻结，不用“看起来在更新”的假信号。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
Evaluator
  ├─ port 8765 ── PolicyService_0 (CPU) ──┐
  ├─ port 8766 ── PolicyService_1 (CPU) ──┤
  ├─ ...                                  ├── Shared VLA server (GPU)
  └─ port 8765+N-1 ── PolicyService_{N-1} ┘
```

- 每个 `PolicyService` 独立进程/线程，独立 `Portrait`/`TaskState`，独立队列；不共享可变任务状态。
- 共享 VLA server：异步批处理；per-port 请求队列；超时/降级；GPU 显存隔离（单模型）。
- CPU 控制器：图像预处理、特征、伺服、动作适配、安全；不抢 GPU。
- 端口服务从 8765 起连续绑定；健康检查；优雅关闭；`reset()` 幂等。

### 3.2 接口契约

```python
class Policy:
    def reset(self, meta): ...
    def get_action(self, obs) -> np.ndarray: ...
```

- `reset(meta)`：清 `TaskState`；保留 `Portrait`；初始化任务卡/目标缓存；不重置端口指纹。
- `get_action(obs)`：返回 `(H_c, action_dim)`；`meta.token` 每次带；动作有限、限幅。
- `obs`：四路 RGB、双臂关节/EE/夹爪、`lower_body`、语言；可选 `obs_delta_indices`。
- 时间：记录 `t_recv/t_send`；估计 `f_c/RTT`；p95 超阈值降级。

### 3.3 每端口状态机

```text
INIT
  ├─ load task card (language match)
  ├─ load portrait (persisted)
  └─ if portrait.confidence < θ: NOMINAL
NOMINAL
  ├─ VLA plan + pure feedforward
  ├─ collect (ΔEE, Δfeature) if calibration-friendly
  └─ if confidence ≥ θ: SERVO
SERVO
  ├─ PBVS far / FLEET-UVS near
  ├─ contact: normal reduction
  └─ edit detected: HOLD → RELOCALIZE → REPLAN
HOLD
  ├─ stop / retract 1cm
  ├─ re-localize target
  └─ resume or fail gracefully
RECOVER
  ├─ task-card recovery action
  ├─ max retries
  └─ fallback VLA / fail
DONE / FAIL
```

### 3.4 `get_action` 伪代码

```python
def get_action(obs):
    t0 = now()
    task = card_for(obs.language, portrait)
    update_timing(portrait, t0)
    update_phase(task, obs)

    plan = plan_cache.get(task.id)
    if plan is None or plan.stale(obs):
        plan = vla.request_async(obs, task)
        if plan is None:
            return hold_or_retract(obs)

    goal = retrieve_goal(task, obs, portrait)
    e = servo_error(obs, goal, task, portrait)

    if task.phase == "contact" or not portrait.servo_ready():
        delta = zeros()
    else:
        delta = clip(portrait.Kp * e + portrait.Kd * de, ...)
        if task.calibration_friendly and excited(obs):
            portrait.update_jacobian(delta_ee, delta_feature)

    a = adapt_action(plan[0:H_c], delta, obs, portrait)
    a = safety_clip(a, obs)
    return a
```

### 3.5 任务卡 schema 与 LLM 编译器

任务卡是静态 JSON（见想法区示例）。字段：

- `task_id`、`language_aliases`；
- `stages[]`：`name/phase/feature/success/servo/calibration_friendly/recovery`；
- `generalization_notes`：5 类泛化轴；
- `safety`：速度/力代理/重试上限；
- `source`/`confidence`。

LLM 编译流程：

```text
official instructions + demo stats + failure priors + API constraints
        │
        ▼
LLM draft (JSON, with source/confidence)
        │
        ▼
schema / safety / observability checks
        │
        ▼
human review + freeze
        │
        ▼
static JSON in submission (no LLM weights)
```

在线匹配：

1. 精确匹配 `task_id`/别名；
2. 关键词/规则匹配；
3. 用 VLA 自己的 text encoder 算 32 卡相似度（同 checkpoint）；
4. 通用卡回退。

**注意**：任务卡不是时间表；阶段由观测/特征/门控触发，不由固定时间硬编码。

### 3.6 安全

- 动作有限性检查；NaN/Inf → hold。
- 关节/EE 限位；速度/加速度限幅；单步修正上限 1cm/0.05rad。
- 接触段法向缩幅/低通；力代理（电流/关节误差）超阈值 → 回退。
- 编辑检测 → 停/回撤 1cm → 重定位；最大重试。
- VLA 超时 → 旧 plan/hold；不无限等待。
- 端口隔离：任务态不跨端口；指纹不含任务观测。

## 4. 实验设计与门

### 4.1 离线数据审计（G0/G1/G2）

1. **G0 字段审计**：32 数据集 `meta/info.json` 的 `camera_params`、`state_d435`、`action.pivot`、`lower_body`、episodes/frames；确认无缺失/异常。
2. **G1 头部姿态**：32 任务全量/留任务拟合；报告位置/姿态 R²、最大残差、分任务残差；检查极端姿态。
3. **G2 腕部**：标称 K/畸变；手眼拟合/重投影；`image_resize` 缩放检查；桌面平面拟合。
4. **动作适配**：`pivot/TCP/gripper` 分布；`example_env.py` 回放；符号/顺序检查。
5. **数据泄漏**：按 session/物体/背景分组；相邻帧不跨 split。

### 4.2 仿真（G3）

- 3 个任务族：peg-in-hole（PlugInEthernet/PlugCharger）、hang/stack（HangCup/StackBowls）、zip/unlock（ZipUp/Unlock）。
- 扫 `H_c ∈ {3,5,8}`、`K_p/K_d`、RTT ∈ {0,50,100,150}ms、图像噪声/遮挡/初始偏移。
- 指标：收敛时间、横向/深度误差、超调、成功率、p95 延迟。
- 通过：横向 ≤2mm、深度 ≤3mm、2s 内 ≥95%；RTT 0–150ms 稳定。
- 失败：降增益/加 chunk；只做 PBVS。

### 4.3 单任务真机（G4）

- 5 个代表任务：PlugInEthernet（插入）、HangCup（挂）、ZipUp（拉链）、StackBowls（叠）、FoldTowel（变形，防回归）。
- 每任务 5 次 A/B：portrait+servo off/on；同初始条件；记录成功、步骤分、耗时、p99 延迟、恢复次数。
- 通过：至少 3/5 任务 +10pp；FoldTowel 不回归 >5pp。
- 失败：不提交 servo 版本；只保留任务卡/动作适配。

### 4.4 多端口干跑（G5）

- 4 个端口并发；不同相机参数/初始姿态/延迟；模拟 N 端口。
- 检查：端口隔离、`reset()` 干净、指纹不串、内存不涨、p99 ≤150ms、无跨端口任务态。
- 通过：4 端口 32 任务干跑无崩溃/无串扰；端口指纹在 episode 间保留。
- 失败：回退单端口/基线。

### 4.5 人为干扰（G6）

- 仿真/真机注入：移动目标、遮挡、拿走物体、人的手进入视野。
- 指标：检测延迟 ≤200ms；恢复成功率 ≥70%；不碰撞。
- 失败：只做离线标注/不线上触发；保守回退。

### 4.6 消融（G8）

| 消融 | 问题 | 预期 |
|---|---|---|
| portrait on/off | 每端口标定是否涨点？ | on > off，尤其多端口 |
| low-dim vs full RLS vs static | 低维残差是否更稳？ | low-dim ≥ full RLS；full RLS 可能发散 |
| task card vs generic | 阶段/特征是否涨点？ | card > generic，接触任务更明显 |
| relative vs absolute goal | 位置/人为干扰是否涨点？ | relative > absolute |
| chunk 3/5/8 | 反馈周期 vs 稳定性 | 5 最佳折中；高 RTT 8 |
| head pose linear vs quadratic | 线性是否够？ | 线性够；二次仅边缘 |
| wrist nominal vs online hand-eye | 在线修正是否必要？ | 多端口 on > nominal |

## 5. 竞赛策略

### 5.1 算术

- `S = (1/32) Σ p_t`；320 trials 下 `p≈0.25` 的 SE≈2.42pp，`p≈0.5` 的 SE≈2.80pp。
- human 轴 = 2/10 = **20%**；human +10pp → 全局 +2pp。
- 10 个接触任务各 +15pp → 全局 +4.7pp；16 个各 +10pp → +5.0pp。
- 两项叠加保守 +4–7pp；乐观 +8–10pp；必须配对 A/B 证明。
- 公开榜单头尾 9.2pp；真实端口/测试者差异可能更大；**不要假设 +2pp 一定升名次**。

### 5.2 任务组合（先验，待单任务通道更新）

- **A 档：端口标定/伺服优先（19 个）**：HangCup、DisconnectEthernet、ToolboxStorage、PlugCharger、Unlock、ArrangeTestTubes、PourOutMedicine、OrganizeStationery、PackBag、ZipUp、PaperCupStacking、StorePaddle、StoreCups、PlugInEthernet、StackBowls、StoreEarphones、PackPhone、OrganizePencilCase、SyringeWaterTransfer。
- **B 档：VLA 优先（13 个）**：FruitCollection、PackDoll、FruitSorting、ColorArrangement、PlacePhotoFrame、OrganizeBookshelf、PickOutBatteries、OrganizeTools、FoldTowel、ArrangePlates、SpellRobot、ConveyorSorting、RemovePinnedNote。
- **C 档：低投入/观察**：单任务通道里 `p_t` 接近 0 且失败在早期感知/抓取的任务；保留 VLA 基线，不投伺服工程。

这张表是**先验**，不是结论。单任务通道测完后，用 `q_t`（失败发生在最后 3 厘米的比例）× `Δ`（端口标定/伺服条件增益）/ `cost_t` 重排；每测 3–5 个任务更新一次。

### 5.3 私有 mini-board

- 分层选 8 个：2 Easy / 3 Medium / 3 Hard；覆盖插入、挂、叠、拉链、变形、人为干扰。
- 每任务 5 次配对 A/B；同初始条件、同端口、A/B 交替；记录成功、步骤分、p99、恢复次数。
- 统计：配对差值 bootstrap 95% LCB；`CVaR_20%`（最差 20% 任务的平均成功率）。
- 升级规则：`LCB(ΔS) > 0` 且 `CVaR` 不降；否则保留基线。
- holdout：留 2 个任务不做 A/B，只做最终验证，降低 mini-board 过拟合。

### 5.4 提交节奏

- 若允许多次提交（需邮件确认）：先交**安全基线**（官方 WLA + chunk 30 + 官方 API 适配）锁“更早提交”的 tie-break；再交通过门的 FLEET-PORTRAIT 版本。
- 若只允许一次：先用单任务通道把版本打磨稳定，再交最终版。
- 不把 320 trials 浪费在“从零训 6B”“完整世界模型”“32 任务各训一个策略”上。

## 7. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定为第二个模型 | 在线只有 VLA 一个学习模型；任务卡是静态 JSON；指纹/伺服无学习权重；提交材料写清楚 |
| LLM 任务卡被当模型 | 合规争议 | LLM 仅离线草稿；提交物无 LLM 权重；人类审核/重写；任务卡可审计 |
| 头部姿态跨任务失效 | PBVS 偏差 | G1 全量验证；残差大时只用姿态/加视觉更新/回退腕部 |
| 手眼激励不足 | FLEET-UVS 不收敛 | 任务卡标记可标定性；低维残差；置信度门控；回退标称/纯 VLA |
| RLS 发散 | 抖动/超调 | 强正则、忘记因子、单步限幅、连续失败冻结；完整 RLS 只做对照 |
| 透明/反光/变形 | 特征丢失 | 只对刚体任务启用；腕部 2D + 夹爪滞止兜底；任务卡标记不可用 |
| 端口重启/指纹丢失 | 冷启动变慢 | 持久化端口指纹；标称回退；不假设端口顺序 |
| 跨端口任务态泄漏 | 违反隔离 | 默认不共享任务观测；指纹只含机器人级参数；代码审计 |
| 远程 RTT 高 | 伺服带宽不足 | 5 步 chunk；RTT 测量；预测/降增益；p95 超标回退 8–10 步 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap LCB、CVaR、重复实验；320 trials SE≈2.4pp |
| 合成榜单误导 | 工程投错任务 | 只当预览上限；私有 mini-board 决定优先级；不追任务排名 |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |
| 安全 | 回撤/重抓碰撞 | 限速/限幅/最大重试；编辑检测即停；零 pivot 回退 |
| `pivot` 语义不一致 | 动作被拒/机器人不动 | 先用 `example_env.py`/单任务通道验证；保留零 pivot 回退 |
| 提交次数限制 | 无法多次 A/B | 邮件确认；单任务通道先验证；一次提交则保守 |
