# 第 44 轮（新循环第 1 轮） · Tool-Cert × Dynamics-Cert：把「工具调用」与「动力学」纳入外部能力与闭环时滞的证书闭环（四层架构 v9）

> 承接第 43 轮 v20（Persona-Cert × Concurrent-Cert）。v20 自陈最大风险是「共形边际覆盖被欺骗 + 多用户契约空集」，但它仍压着两个更基础的未言明假设：**(H1) 证书系统调用的每个能力都是内部、瞬时、可信的纯函数**——真实具身系统却不断调用外部工具/云模型/求解器/其他机器人/数据库，工具带有副作用、时延、版本漂移与不可信输出，证书闭包会在调用边界处静默破裂；**(H2) 证书新鲜度只由一阶速度界支配**——真实闭环的总时延（感知 + 排队 + 工具 + 计算 + 执行）与加速度/模式切换会让一阶租约 `m−λ(t−τ)` 在高速机动时高估裕度，在时滞下甚至使闭环失稳。本轮灵感词「工具调用」「动力学」精确命中这两个假设：**工具调用**迫使我们把工具从「透明 oracle」降格为「带契约的外部主体」，用证书随行调用、效果令牌与污点隔离把外部性关进证书闭包；**动力学**迫使我们把租约从一阶速度外推升级为二阶加速度外推，并把闭环时滞纳入稳定性证书。二者耦合处才是真正的新问题：**工具时延既消耗证书新鲜度，又消耗闭环时滞裕度**；若两个预算各自按边际证明，联合尾部会一起越界，而每个局部证书仍然显示为绿。

## 0. 直觉与动机

**灵感 1（工具调用 → 「工具是外部主体，不是纯函数」：调用前持证、调用中受控、调用后验真、失败留白）**：过去我们默认「查一个 VLM、调一个规划器、问一次云端」得到的结果天然属于证书系统。但工具调用至少带来四种外部性：**语义外部性**（工具版本更新后输出含义变了）、**时间外部性**（结果返回时世界已不是调用时的世界）、**副作用外部性**（开门、下单、发消息等调用不可幂等重试）、**信任外部性**（工具输出可能被污染，甚至包含指令注入）。因此把工具建模为带契约的外部转移 τ=(前置条件, 后置关系, 读写/副作用足迹, 失败模型, 版本哈希, 时延契约, 坐标帧)。一次调用只有在**调用前前置条件被证书满足、调用中在时延/权限预算内、调用后结果通过后置校验且时间/坐标帧对齐**时，才允许其产物进入证书闭包；否则产物进入**隔离区 Q**，作为一等的 `unknown`，只能触发单调降级，绝不能被强转为 `safe`。对不可幂等副作用，使用**效果令牌 + prepare/commit/verify 事务**：超时后不盲目重试，先记 `unknown` 再对账，保证至多一次。对工具输出做**污点格**传播：输出默认是 `untrusted_data`，不是指令，永远不能写入安全关键谓词。一句话：**工具的返回值不是事实，只是待验真的证据**。

**灵感 2（动力学 → 「加速度与时滞是证书的隐藏状态」：一阶租约在机动时静默高估，在时滞下可能失稳）**：v20 的租约只用了位移的一阶界 `||x(t)−x(τ)|| ≤ v_max·Δ`，但真实状态有加速度甚至冲击。若 `v_max=2 m/s, a_max=8 m/s², Δ=0.2s`，一阶界给出 0.4m，二阶真实上界是 `2×0.2 + 0.5×8×0.04 = 0.56m`；在 margin 对状态 Lipschitz 的假设下，这 0.16m 的缺口足以让守卫把 `m<θ` 当成 `m≥θ`，静默放行。更麻烦的是**时滞**：工具调用把「感知—规划—工具—计算—执行」串成一条有延迟的反馈环，控制器实际用的是 `δ` 秒前的证书；延迟在频域引入 `ωδ` 相位滞后，当 `δ` 超过由相位裕度给出的 `δ_max` 时闭环会振荡甚至发散。工具时延的**尾部分布**（排队、重试、版本冷启动）又远大于均值，因此必须区分两个预算：**新鲜度预算** `δ_fresh(m,θ)`（信息还能用多久）与**时滞裕度** `δ_max`（闭环还能稳多久）。一次调用可被接纳，当且仅当 `δ_p99 ≤ min(δ_fresh, δ_max)`。一句话：**一阶租约只证明「信息旧了」，二阶 + 时滞证书才证明「系统还稳」。**

**灵感 3（耦合 → 「工具调用图把动力学变成时滞系统」：串行累积、并行换不到免费的午餐）**：真实规划不是单次调用，而是一张**工具调用图**：先 VLM 语义，再检索，再几何证书，再安全检查，可能并行展开分支。串行调用的时延相加，margin 的二阶衰减按和的平方增长；并行调用能缩短关键路径，但会争抢 CPU/带宽，把排队尾时延推高——所以「并行 = 免费新鲜度」在尾部是假的。更隐蔽的是**版本漂移**：工具升级同时改变时延分布与语义后置条件，使原本校准好的 `δ_max` 与契约都失效。于是新增 IP-62 做工具故障 × 时延 × 加速度的**联合尾部压力测试**，用 CEGIS 在 `δ_fresh` 与 `δ_max` 的边界上找反例，专门搜「每个边际都合格、联合却越界」的场景。一句话：**工具调用的真正动力学，是调用图的时延传播；证书必须对整条关键路径封闭，而不是对每个工具分别闭包。**

**耦合升级**：TCE（工具契约引擎）把外部能力编译成可校验的前/后置契约、效果令牌与污点策略；DDCR（时滞动力学证书运行时）把二阶租约、双预算准入与 contraction/delay 证书落到守卫；TDV（工具-动力学验证器）在仿真里注入工具故障、版本漂移与尾时延，做联合反例回灌。四层架构由此从 v8 的「人格 + 并发」升级为 v9 的「人格 + 并发 + 工具外部性 + 闭环时滞」。

## 1. 形式化定义（增量：定义 44–49）

**定义 44（带契约的工具与证书随行调用）**：工具 τ=(Σ_τ, A_τ, π^pre_τ, π^post_τ, E_τ, Φ_τ, v_τ, Δ_τ, c_τ, F_τ)。其中 Σ_τ 为输入/输出类型与坐标帧，A_τ 为能力/权限集合，π^pre_τ 为作用在已认证状态与参数上的前置谓词，π^post_τ 为 (x, args, y, x') 上的后置关系，E_τ=(R_τ,W_τ,S_τ) 为读集/写集/外部副作用集，Φ_τ 为失败模型（超时、部分、不一致、版本漂移、对抗输出），v_τ 为不可变版本哈希，Δ_τ 为时延契约（硬界或共形 q-分位上界），c_τ 为成本预算，F_τ 为结果帧/时间到证书帧/时间的对齐映射。**证书随行调用** `CertInvoke(τ,args,x)` 返回 `Cert(y,x',v_τ,F_τ,ρ_τ)` 或失败 `⊥_φ`；只有满足
`x⊨π^pre_τ ∧ args∈dom(τ) ∧ 返回时延≤Δ_τ ∧ v_τ=版本锁定值 ∧ F_τ 对齐 ∧ (x,args,y,x')⊨π^post_τ`
时，`y` 才被赋予证书 ρ_τ。**注**：`y` 自带 `(版本, 帧, 时间, 污点)` 四元印章，缺一不可。

**定义 45（工具闭包与隔离区）**：证书状态 C=(C_core, C_tool, Q)。C_core 为内部证书，C_tool 为通过定义 44 的工具产物，Q 为所有未认证/未知/超时/漂移结果的隔离区。守卫 G 只允许读 `C_core ∪ C_tool`，禁止读 Q。**定理 1（闭包 sound）**：若每次进入 C_tool 的写入都通过定义 44，且每次失败都进入 Q，则任意工具调用序列都不会让未认证外部产物影响守卫决策。**证明梗概**：对调用序列归纳；未认证结果无路径到达 G 的读集，且 Q 中元素不可被隐式提升为 safe。**推论**：`unknown` 是安全意义上的吸收态——只能重新认证或触发单调降级，不能被「默认安全」填平。

**定义 46（效果令牌、事务调用与污点隔离）**：对不可幂等副作用，定义意图 `e=(id_τ, hash(args), hash(x))` 与效果令牌 ε。事务三阶段为 prepare（预留副作用、登记日志）→ commit（执行外部效果）→ verify（后置校验）。**至多一次**：对同一 id_τ 至多一次 commit；超时只记 `UNKNOWN`，禁止盲目重试，只能凭幂等键或效果日志对账。污点格 L={⊥, trusted, derived, untrusted_data, instruction}，工具输出默认为 untrusted_data。**污点策略**：`untrusted_data ∩ writes(I.critical_vars)=∅`，且工具输出不得进入系统指令通道。**定理 2**：唯一效果令牌 + 持久 commit 日志 ⟹ 不产生重复外部副作用；污点策略 + 定义 40 的非干扰 ⟹ 工具输出无法通过指令注入改写安全关键谓词。

**定义 47（二阶新鲜度租约）**：设 margin m 关于状态是 L_m-Lipschitz，且真实轨迹满足 `||ẋ||≤v_max, ||ẍ||≤a_max`。租约 ℓ=(m,τ,λ_1,λ_2,κ)，其中 `λ_1=L_m v_max, λ_2=L_m a_max`。**新鲜度判据**：`m − λ_1(t−τ) − ½λ_2(t−τ)² ≥ θ`。**命题 1（二阶 sound）**：由二阶 Taylor 界 `||x(t)−x(τ)|| ≤ v_maxΔ + ½a_maxΔ²`，有 `m(t) ≥ m(τ) − L_m(v_maxΔ + ½a_maxΔ²)`，故判据成立时真实 margin 必不低于 θ。**命题 2（一阶反例）**：若 `a_max>0, Δ>0`，取 `λ_2=0` 可在一阶界仍显示安全时出现真实 margin `<θ`，缺口约为 `½L_m a_maxΔ²`。**推论**：守卫必须计算 `δ_fresh(m,θ)=sup{Δ: m−λ_1Δ−½λ_2Δ²≥θ}`，即二次方程 `½λ_2Δ²+λ_1Δ−(m−θ)=0` 的正根。

**定义 48（时滞动力学证书与双预算准入）**：闭环 `ẋ=f(x,u(t−δ),w)`，总时延 `δ=δ_sense+δ_queue+δ_tool+δ_comp+δ_act`。动力学证书 D=(V,ρ,δ_max,γ,X_inv)：V 为 contraction/Lyapunov 度量，满足 `d/dt V(δx) ≤ −ρV(δx)+γ||δw||`；X_inv 在 `δ≤δ_max` 下正不变；δ_max 由相位裕度 `δ_max≈φ_m/ω_c` 或 Lyapunov-Krasovskii 泛函离线给出。**双预算准入**：工具调用被接纳，当且仅当 `δ_p99 ≤ min(δ_fresh(m,θ), δ_max)`，其中 δ_p99 为工具调用图关键路径时延的共形上界/硬界。**定理 3（双预算 sound）**：若 `δ≤δ_max` 且二阶租约在整个使用窗口内有效，则闭环保持在 X_inv 且守卫 margin 不低于 θ；任一预算被击穿则必须降级。**注**：若工具 commit 触发模式切换或速度跳变，则按冲击事件处理，局部重置加速度界并强制重认证，绝不沿用切换前的租约。

**定义 49（定时工具调用图与证书代数）**：调用图 G=(V,E) 为 DAG，节点 i 带时延契约 Δ_i 与证书截止期 d_i。关键路径 `π` 的时延 `δ(π)=Σ_{i∈π}Δ_i`；独立并行分支取 `max_i Δ_i`，但若共享资源则加排队界 Q_eff。margin 沿路径传播：
`m_out = m_in − L_m(v_max·δ(π) + ½a_max·δ(π)²) − L_m Q_eff`。
**端到端证书地平线**：`H(π)=δ_fresh(m_in,θ)−δ(π)`。**定理 4（组合 sound）**：若每个节点都按定义 44 持证，且每条关键路径满足 `δ(π) ≤ min(δ_fresh(m_in,θ), δ_max)`，则整张调用图的输出证书 sound。**推论（并行不是免费午餐）**：并行可缩短关键路径，但因二次项与排队尾时延，margin 衰减不一定按并行数线性下降；当 `Q_eff` 增大时，并行甚至可能让 H(π) 变小。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-60 TOOL-CONTRACT-ENGINE（工具契约引擎 TCE）

1. **契约注册与编译**：工具 schema、权限、前/后置谓词、版本哈希、坐标帧、时延分布 → 可机检契约；按 persona/任务做最小权限白名单。
2. **证书随行调用网关**：调用前检查 `π^pre` 与帧对齐；调用中执行超时/成本约束；调用后校验 `π^post`、版本与时间印章；失败统一进隔离区 Q。
3. **效果令牌与事务日志**：不可幂等副作用走 prepare/commit/verify，超时不重试、只对账；持久日志支持崩溃恢复与至多一次审计。
4. **污点与指令隔离**：工具输出默认 `untrusted_data`，禁止写入 `I.critical_vars`，禁止进入系统提示/工具选择策略；需要可信时只能走独立 verifier 提升。

### 2.2 IP-61 DELAY-DYNAMICS-CERT-RUNTIME（时滞动力学证书运行时 DDCR）

1. **二阶租约表**：每任务维护 `(m,τ,λ_1,λ_2,κ)`，λ 由在线估计的 `v_max,a_max` 与 `L_m` 给出；守卫用二次根算 `δ_fresh`。
2. **双预算准入器**：对每条工具调用图测量/共形估计 `δ_p99`，与 `δ_fresh`、`δ_max` 比较；通过才放行，否则单调降级（缩短租约、降速、换无工具策略）。
3. **时滞证书库**：按模式离线计算 contraction 度量、`δ_max` 与 X_inv；运行时模式切换只在已认证包络内发生，切换点强制重认证。
4. **工具调用调度器**：关键路径 + 截止期调度，安全监控预算硬隔离；禁止在安全监控链路上做无界重试/冷启动；并行分支数 b 受资源与尾时延约束。

### 2.3 IP-62 TOOL-DYNAMICS-VALIDATOR（工具-动力学验证器 TDV）

1. **工具故障与时延注入**：超时、部分返回、乱序、版本漂移、帧错配、恶意输出；覆盖工具调用图的每条边。
2. **联合尾部压力测试**：在 `(δ_p99, a_max, 模式切换)` 三维联合分布上扫尾，专找「边际合格、联合越界」的共模反例。
3. **事务/污点审计**：重复副作用、丢失 commit、未授权写 `I.critical_vars`、指令注入路径；与定义 46 的日志对账。
4. **CEGIS 反例回灌**：以 `H(π)<0` 或 `δ_p99>min(δ_fresh,δ_max)` 为边界，生成反例回灌 TCE 契约与 DDCR 的 δ_max/租约参数。

### IP-60 TCE：契约调用、隔离与事务

```
def certified_invoke(tool_id, args, x, budget, version_pin):
    tau = registry.resolve(tool_id, version_pin)
    if tau is None:                 return Quarantine('unknown_tool')
    if not tau.pre(x, args):        return Deny('precondition')
    if not tau.frame.aligns(x):     return Deny('frame')
    intent = Intent(id=uuid(), tool=tau.id, args=hash(args), pre=hash(x))
    journal.prepare(intent)         # 预留副作用, 登记效果令牌
    t0 = monotonic_now()
    try:
        y = call_with_timeout(tau, args, min(tau.delta, budget))
    except Timeout:
        journal.mark_unknown(intent)            # 不盲目重试
        return Quarantine(intent, reason='timeout')
    dt = monotonic_now() - t0
    if dt > tau.delta:              return Quarantine(intent, 'late')
    if y.version != tau.version:    return Quarantine(intent, 'version_drift')
    if not tau.frame.aligns(y.frame, x.frame):
        return Quarantine(intent, 'frame_mismatch')
    if not tau.post(x, args, y, y.next_state):
        return Quarantine(intent, 'postcondition')
    journal.commit(intent)          # 持久 commit, 至多一次
    return Certificate(y, tau=tau, version=y.version, frame=y.frame,
                       time=monotonic_now(), taint=UNTRUSTED_DATA)

def admit_guard(cert, guard):
    if cert.state != CERTIFIED:                     return False
    if not frame_align(cert.frame, guard.frame):    return False
    if taint_join(cert.taint, guard.read_taint) not in {⊥, trusted, derived}:
        return False
    return True
```

**正确性要点**：`Q` 不可被守卫读取；`unknown` 无隐式提升路径；`journal.commit` 的幂等键保证至多一次；`taint` 默认 untrusted_data 阻断指令注入写穿。

### IP-61 DDCR：二阶租约、双预算与调用图

```
def second_order_lease(m, tau, v_max, a_max, Lm, kappa):
    return Lease(m=m, tau=tau, lam1=Lm*v_max, lam2=Lm*a_max, kappa=kappa)

def delta_fresh(m, theta, lam1, lam2):
    if m <= theta:      return 0.0
    if lam2 <= 1e-12:   return (m - theta) / lam1
    disc = lam1*lam1 + 2.0*lam2*(m - theta)
    return (-lam1 + sqrt(disc)) / lam2          # 二次方程正根

def lease_margin(lease, t):
    dt = t - lease.tau
    return lease.m - lease.lam1*dt - 0.5*lease.lam2*dt*dt

def dual_budget_admit(lease, theta, delta_p99, delta_max, t, eps=1e-9):
    m_eff = lease_margin(lease, t)
    if m_eff < theta:   return False, 'stale'
    if delta_p99 > delta_fresh(m_eff, theta, lease.lam1, lease.lam2):
        return False, 'freshness_budget'
    if delta_p99 > delta_max:
        return False, 'delay_margin'
    return True, 'ok'

def tool_graph_latency(graph, latency_p99, queue_bound):
    # 关键路径 + 资源争用排队上界, 串行相加/独立并行取 max
    return longest_path(graph, latency_p99) + queue_bound(graph)

def guard_with_tool(cert, lease, graph, theta, delta_max, t):
    if not admit_guard(cert, guard):
        return downgrade_monotone('quarantine')
    d = tool_graph_latency(graph, p99_estimator(graph), queue_bound(graph))
    ok, why = dual_budget_admit(lease, theta, d, delta_max, t)
    return allow(cert) if ok else downgrade_monotone(why)
```

**正确性要点**：`delta_fresh` 来自定义 47 的二次界，故不会误用陈旧 margin；`delta_max` 来自定义 48 的 contraction/LK 证书，故不会在失稳时滞下放行；两者任一不足即降级。

### IP-62 TDV：联合尾部 fuzz 与 CEGIS

```
def joint_tail_fuzz(n, delta_range, accel_range, fault_set):
    ce = []
    for _ in range(n):
        delta = sample_tail(delta_range)        # 尾部分位, 非均值
        accel = sample_tail(accel_range)        # 高加速度/模式切换
        faults = sample(fault_set)              # 超时/部分/乱序/漂移/投毒
        trace = run_sim(tool_latency=delta, accel=accel, faults=faults,
                        use_tce=True, use_ddcr=True)
        if trace.guard_certified and trace.safety_violated:
            ce.append((delta, accel, faults, trace))
    return ce

def cegis_boundary(leaves, eps):
    # 在 H(pi)=0 与 delta_p99=min(delta_fresh,delta_max) 边界搜索
    frontier = pareto(leaves, keys=['safety_margin', 'latency', 'accel'])
    return refine(frontier, eps)
```

**正确性要点**：联合采样覆盖 `(δ_p99, a_max, 模式切换)` 的尾部相关结构；反例回灌契约与 δ_max，形成与 v20 相同的 CEGIS 闭环。
