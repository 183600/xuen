### 第 3 轮灵感驱动研究记录

**灵感词**：实时性、预训练

**直觉与动机**：
上一轮 KEMPC 把常识规则作为软约束嵌入在线 MPC，并在每个控制周期同步生成/验证 KC、DCC。这在「正确性」上自洽，却暴露了两个工程软肋：

1. **实时性**：每周期求解 N=20 的 QP，再对最多 50 条规则做「每条采样 100 条轨迹」的存在性验证，最坏执行时间不可控，与 50Hz 硬实时冲突；规则越多越慢。
2. **常识闭塞**：规则与权重靠人手写，覆盖不足时会退化成保守或误导策略（上一轮 R19）。

「预训练」给出互补思路：人类走路并不每步重解最优控制，而是把大量经验固化成反射/先验，只在异常时才调用慢速推理。对应到系统，就是把「慢而强」的离线计算（常识、动力学、证书验证）**摊销**到离线，在线只做「快而轻」的推理与**分级认证**。

**关键洞见**：构建「预训练证书先验 + 实时分级认证」（Pretrained Certificate Prior + Real-Time Tiered Certification, PCP-RTTC）：

- **预训练常识先验策略** π_θ(a|x,g)：以任务/地形/模式 token g 为条件，用「任务代价 + 常识违规代理损失 + 覆盖正则」预训练，使快路径动作本身更贴近 KC/DCC 可行流形；
- **证书评论家** C_ψ(x,π)：预测软常识规则是否通过，并给出不确定半径 U_ψ，仅用于**路由**（是否触发慢路径），不承担最终安全；
- **认证核心 / 学习外壳分解**：评论家高置信区域直接走快路径，低置信或分布外区域降级到精确 KC/DCC 验证或摊销式 KEMPC；
- **实时性证书** RTC：显式给出最坏周期延迟上界、超时概率与「任意时刻可中断」语义；慢路径超时则执行预认证的 CBF 备份控制器；
- **安全锚点转移**：安全性由「始终运行的硬监控 + CBF 安全过滤器 + 预认证备份」保证，评论家只做调度。这样避免把安全押在神经网络泛化上。

一句话：把上一轮「每周期全量证书」改成「离线摊销 + 在线分级 + 超时备份」，既缓解实时性瓶颈，也用覆盖感知的回退缓解常识闭塞。

**形式化目标**：
1. 定义任务分布 𝒟 与预训练目标：min_θ E_{τ~𝒟}[J_task + λ·V_kc + μ·V_dcc] + η·Reg_coverage；
2. 定义证书评论家 C_ψ: 𝒳×𝒜^H → [0,1]^M × ℝ⁺（通过概率 + 不确定半径）；
3. 定义认证核心/学习外壳分解：Core_ε = {x : U_ψ(x) ≤ ε}，Shell_ε = 其余；
4. 定义实时性证书 RTC = (T_cycle, T_wc, p_miss, u_backup)，T_wc 为最坏周期延迟上界；
5. 定义分级准入自动机：FAST / VERIFY / BACKUP 三态，任意时刻可中断；
6. 证明（在覆盖与校准假设下）硬安全不弱于上一轮，且全量认证周期比例有下界；
7. 给出摊销间隙（amortization gap）与「实时性—安全性—常识质量」三维权衡曲线。

**本轮最大风险**：预训练评论家的「分布外静默失效」——在线状态一旦落到训练分布之外，学习外壳若因校准漂移被误判为认证核心，系统会在没有任何报错的情况下放行不安全动作；这种失效比「超时」更难检测，因为系统看起来始终实时且流畅。

### IP-465 预训练常识先验策略（PKP）

```python
class PretrainedKnowledgePolicy(nn.Module):
    def __init__(self, state_dim, act_dim, horizon, cond_dim):
        super().__init__()
        self.enc = nn.Sequential(nn.Linear(state_dim + cond_dim, 256),
                                 nn.SiLU(),
                                 nn.Linear(256, 256), nn.SiLU())
        self.actor = nn.Linear(256, horizon * act_dim)

    def forward(self, x, g):
        h = self.enc(torch.cat([x, g], dim=-1))
        return self.actor(h).view(-1, self.horizon, self.act_dim)

def pretrain_policy(policy, critic, dataset, epochs, cfg):
    """预训练目标：任务代价 + 常识违规代理 + DCC 惩罚 + 覆盖正则。"""
    for batch in loader(dataset, epochs):
        u = policy(batch.x0, batch.goal)
        J_task = cfg.task_cost(batch.x0, u)
        # 软标签代理：C_ψ 预测的违规概率（可微）
        p_pass, _ = critic.predict(batch.x0, u)
        J_kc = -(p_pass * batch.kc_labels).sum(dim=-1).mean()
        J_dcc = cfg.mu * torch.relu(cfg.kappa - batch.dcc_margin).mean()
        # 覆盖正则：鼓励在稀有簇上也保持低违规（防长尾闭塞）
        J_cov = cfg.eta * batch.rare_weight * (-p_pass.mean(dim=-1))
        loss = J_task + cfg.lam * J_kc + J_dcc + J_cov
        loss.backward()
        cfg.opt.step(); cfg.opt.zero_grad()
```

### IP-467 认证核心 / 学习外壳（CCS）

```python
class RegionClassifier:
    CORE_SAFE, CORE_UNSAFE, SHELL = 0, 1, 2

    def __init__(self, eps_radius: float, margin: float):
        self.eps = eps_radius
        self.margin = margin

    def classify(self, p_pass: Tensor, radius: Tensor) -> int:
        if radius > self.eps:
            return self.SHELL                    # 不确定 -> 必走精确验证
        if (p_pass >= 0.5 + self.margin).all():
            return self.CORE_SAFE
        if (p_pass <= 0.5 - self.margin).all():
            return self.CORE_UNSAFE              # 明确违规 -> 直接拒绝/重规划
        return self.SHELL
```

### IP-468 实时性证书（RTC）

```python
@dataclass
class RealTimeCertificate:
    T_cycle: float = 0.020        # 50Hz
    T_fast_max: float = 0.002     # 预训练策略前向
    T_monitor_max: float = 0.001  # 硬监控 O(M_hard)
    T_backup_max: float = 0.001   # CBF 备份 O(1)
    p_miss: float = 1e-4          # 慢路径超时概率上界

    @property
    def T_wc(self) -> float:
        return self.T_fast_max + self.T_monitor_max + self.T_backup_max

    def admits_latency(self) -> bool:
        # 慢路径可被任意中断，故硬上界只含快路径 + 监控 + 备份
        return self.T_wc <= self.T_cycle

    def budget_for_slow(self) -> float:
        return max(0.0, self.T_cycle - self.T_wc)
```

### IP-469 分级认证自动机（TCA）

```python
class Tier(Enum):
    FAST, VERIFY, BACKUP = auto(), auto(), auto()

class TieredCertificationAutomaton:
    def __init__(self, policy, critic, region, verifier,
                 kempc, cbf_filter, rtc, monitor):
        self.policy, self.critic, self.region = policy, critic, region
        self.verifier, self.kempc = verifier, kempc
        self.cbf, self.rtc, self.monitor = cbf_filter, rtc, monitor

    def step(self, x, g, deadline):
        # ---- FAST：预训练策略 + 硬监控 + CBF 过滤 ----
        u_pre = self.policy(x, g)[0]
        u_safe = self.cbf.filter(x, u_pre)          # 强制 h(f(x,u)) ≥ (1-α)h(x)
        if not self.monitor.hard_ok(x, u_safe):     # 安全关键规则，永远检查
            return self._backup(x)
        if self.rtc.remaining(deadline) <= 0:
            return self._backup(x)

        # ---- 路由：评论家只决定是否值得走慢路径 ----
        p_pass, radius = self.critic.predict(x, u_safe, g)
        tier = self.region.classify(p_pass, radius)
        if tier == RegionClassifier.CORE_SAFE:
            return u_safe, Tier.FAST
        if tier == RegionClassifier.CORE_UNSAFE:
            # 明确违反软常识：用慢路径重规划，预算不足则备份
            return self._verify_or_backup(x, g, u_pre, deadline)

        # ---- VERIFY：外壳 -> 精确 KC/DCC 或摊销 KEMPC ----
        return self._verify_or_backup(x, g, u_pre, deadline)

    def _verify_or_backup(self, x, g, u_pre, deadline):
        budget = self.rtc.remaining(deadline)
        try:
            if budget >= self.rtc.T_cycle * 0.3:
                u = self.kempc.solve_amortized(x, u_pre, budget)  # 热启动
            else:
                u = self.kempc.solve_exact(x, budget)
            if self.monitor.hard_ok(x, u) and self.cbf.feasible(x, u):
                return u, Tier.VERIFY
        except TimeoutError:
            pass
        return self._backup(x)

    def _backup(self, x):
        return self.cbf.backup_control(x), Tier.BACKUP   # 预认证，O(1)
```

## 3. 实时性预算与复杂度（增量）

| 路径 | 组成 | 时间复杂度 | 典型延迟 | 是否计入硬上界 |
|---|---|---|---|---|
| FAST | PKP 前向 + 硬监控 + CBF | O(d_θ + M_hard + n_x³) | 1–2 ms | 是 |
| 路由 | CC 前向 + 区域判定 | O(d_ψ) | 0.2–0.5 ms | 是 |
| VERIFY | 精确 KC/DCC 或 A-KEMPC | O(M·H + N·n_x³) | 3–10 ms（可中断） | 否 |
| BACKUP | CBF 备份控制 | O(1) | <0.5 ms | 是 |

**硬实时预算**：`T_wc = T_fast + T_monitor + T_backup ≤ 3–4ms < T_cycle = 20ms`。慢路径使用剩余预算，且必须可被 deadline 中断；超时概率 `p_miss` 由离线压测 + 保形界估计。

**相对 v27 的关键变化**：v27 的最坏路径是「每周期全量 QP + 全量规则采样验证」，随规则数线性甚至超线性增长且不可中断；v28 把最坏路径压到 O(1) 备份，慢路径成为「尽力而为」的质量增强。

## 4. 正确性论证（增量）

### 定义 23（预认证安全集与备份控制器）
令 h: 𝒳 → ℝ 为 CBF，S_safe = {x : h(x) ≥ 0}。称 u_backup 为预认证备份，若对任意 x ∈ S_safe，离散 CBF 条件成立：`h(f(x, u_backup(x))) ≥ (1-α)h(x)`，α ∈ (0,1)。

### 定义 24（实时性证书）
RTC = (T_cycle, T_wc, p_miss, u_backup)，满足 T_wc ≤ T_cycle；对任意到达时刻 t，控制器可在 T_wc 内输出一个动作，且当慢路径未完成时必输出 u_backup。

### 引理 23（硬监控 + CBF 的前向不变性）
若初始 x₀ ∈ S_safe，且每个执行动作 u 满足 `h(f(x,u)) ≥ (1-α)h(x)`，则对所有 t，x_t ∈ S_safe。

**证明**：对 t 归纳。h(x_{t+1}) ≥ (1-α)h(x_t) ≥ 0，由 h(x_t) ≥ 0 得 h(x_{t+1}) ≥ 0。∎

### 引理 24（快路径硬安全）
FAST 路径只在 `monitor.hard_ok(x,u)` 且 `cbf.filter` 通过时执行 u，因此执行动作满足全部安全关键常识规则与 CBF 条件，进而由引理 23 轨迹留在 S_safe。

**证明**：TCA.step 中 u_safe 必经 cbf.filter 与 hard_ok 双重检查；CBF 条件由 filter 保证，硬规则由 monitor 保证。∎

### 引理 25（分层准入的集合关系）
记 Exec_v28^full 为「FAST 且评论家判为 Core_SAFE，或 VERIFY 完成并通过」的周期集合；Exec_v28^hard 为「仅通过硬监控 + CBF」的周期集合。则
1. `Exec_v28^full ⊆ Exec_v27`（全量认证周期仍满足上一轮全部 KC/DCC）；
2. `Exec_v28^hard` 满足全部**安全关键**约束，但**不保证**软常识规则；软规则违反概率 ≤ δ_cal + δ_ood。

**证明**：1) Core_SAFE 要求评论家高置信通过且半径 ≤ ε；VERIFY 分支调用精确验证器，二者均等价于或强于 v27 的验证条件。2) hard 分支只强制 hard_ok 与 CBF；软规则由评论家路由，误判由校准误差 δ_cal 与分布外漏检 δ_ood 控制。∎

> 注：这里刻意**不**宣称 Exec_v28^hard ⊆ Exec_v27。快路径跳过软验证，是质量与实时性的显式权衡，必须如实标注为「降级认证」。

### 引理 26（摊销间隙）
设 π_θ 在 𝒟 上相对 KEMPC 最优的次优度为 ε_amort，A-KEMPC 以 π_θ 热启动并在半径 r 的信赖域内求解，代价函数 L-光滑。则
`J_A-KEMPC ≤ J_KEMPC + ε_amort + L·r`，
且强凸情形下热启动把 QP 迭代数从 O(κ log(1/ε)) 降到 O(log(1/ε))（κ 为条件数）。

**证明**：由 L-光滑，信赖域内目标与热启动点目标差 ≤ L·r；热启动点本身 ε_amort-次优；迭代复杂度为标准信赖域/内点结论。∎

### 定理 27（实时任意时刻安全）
若 RTC.admits_latency() 成立、S_safe 非空且 CBF 可行，则每个控制周期都输出一个满足硬安全约束的动作，**与慢路径是否完成无关**；且全量认证周期比例下界为 `1 - p_miss - trigger_rate`，其中 trigger_rate 为进入 VERIFY 且最终备份的比例。

**证明**：由定义 24，慢路径未完成时输出 u_backup；由引理 23、24，u_backup 与快路径动作均保持 S_safe 并满足硬规则。全量认证比例由超时概率与备份触发率直接相减得到。∎

## 5. 预训练课程与实验设计

### 5.1 数据配比与课程
- **地形**：平地/斜坡/台阶/碎石/湿滑，按难度 4:3:2:1 采样，稀有地形过采样。
- **模式**：walking / standing / transition，比例 6:2:2，transition 样本额外加权。
- **课程**：先平地站立/直行，再斜坡与转向，最后动态扰动与滑移；每阶段用上一阶段策略热启动。
- **标签来源**：软 KC 标签与 DCC 裕度均由上一轮**精确验证器**离线打标，杜绝代理奖励自证。

### 5.2 基线
1. v27 全量 KEMPC（无预训练、每周期全验证）；
2. 纯 RL 策略（无证书、无 CBF）；
3. RL + CBF（有安全过滤，无常识证书）；
4. 本文 PCP-RTTC（无覆盖正则 / 无评论家路由 / 无备份 三个消融）。

### 5.3 指标
| 指标 | 定义 | 目标（假设，待验证） |
|---|---|---|
| p99 周期延迟 | 单周期端到端 | < 5 ms |
| deadline miss 率 | 超过 T_cycle 的比例 | < 1e-4 |
| 硬安全违规率 | 跌倒/失稳/碰撞 | 0（仿真内） |
| 软常识违规率 | 软 KC 违反比例 | ≤ δ_cal + δ_ood |
| 慢路径触发率 | 进入 VERIFY 比例 | < 15% |
| OOD 检测 AUROC | 评论家对分布外地形 | > 0.95 |
| 任务回报 | 到达目标/能耗 | ≥ v27 的 95% |

### 5.4 预期结果（占位，待实测）
| 方法 | p99 延迟 | 硬违规 | 软违规 | 回报 |
|---|---|---|---|---|
| v27 KEMPC | 25–40 ms | 0 | 低 | 1.00 |
| 纯 RL | 1 ms | 高 | 高 | 1.10 |
| RL + CBF | 2 ms | 0 | 高 | 1.05 |
| PCP-RTTC（本文） | 3–5 ms | 0 | 低 | 0.97 |

> 关键待验证假设：预训练先验能把慢路径触发率压到 15% 以下，同时不显著牺牲回报；若触发率过高，实时性收益会被慢路径挤占。

## 6. 已知风险与缓解（增量）

| 风险编号 | 描述 | 严重度 | 缓解措施 | 剩余风险 |
|---|---|---|---|---|
| R22 | 评论家分布外静默失效（校准漂移） | 高 | 1) 保形预测给出可经验验证的 δ_cal；2) 覆盖监控 + 嵌入距离 OOD 路由；3) 硬监控 + CBF 始终兜底；4) 定期用精确验证器抽检 | 极端 OOD 仍可能被误判为核心 |
| R23 | 预训练分布偏移 / 违规代理被 reward hacking | 高 | 1) 精确验证器离线打标，不用自证标签；2) 分布鲁棒优化 + 稀有簇过采样；3) 人工审计高影响规则 | 部署分布剧变时先验退化 |
| R24 | CBF 在极端地形不可行或备份不足 | 中 | 1) 多备份模式（站立/蹲伏/急停）；2) 在线可行性检查并升级到慢路径；3) 安全集收缩 | 严重滑移/坍塌下 CBF 前提被破坏 |
| R25 | 预训练成本与再训练周期 | 中 | 1) 增量/持续预训练；2) 缓存慢路径参考轨迹；3) 课程复用 | 新规则上线延迟 |

## 7. 本轮最大风险（最终确认）

**一句话**：**预训练评论家的「分布外静默失效」与 CBF 前提在极端地形下被破坏会叠加：系统仍会表现得实时、流畅，却在无告警的情况下放行不安全动作——这比上一轮的「常识闭塞」更隐蔽，因为失效不再表现为保守或卡顿，而是表现为「一切正常」。**
