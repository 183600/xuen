# 第 66 轮（承接第 65 轮「VISTA 视觉知情安全时序归因」IP-214~223；灵感循环第 1 轮；本轮灵感：「商业模式」×「UniBot」）

> 第 65 轮把"几何可证伪"升级为"故障可归因"，其自述的最大风险很诚实：**归因能力依赖"故障属于有限假设集、且视觉与几何的失效相互独立"两个假设；真实故障常是未知类型的组合，透明/镜面/对抗 patch 会让视觉与几何共享同一个分布外失效源，于是 FIR 把未知复合故障强行归入最近假设、只膨胀错误的球，系统反而因为"已经归因"而更自信地继续执行。** 本轮不往 ℋ 里塞第 7 个假设，也不再加第 6 个模态。前 65 轮共享一个从未被言明的前提：**安全是单个机器人、单次 episode、单个物理系统的属性**。但真实部署里，一份安全结论要跨越不同站点、不同机体、不同客户被反复复用，要由不同主体各自承担一部分后果，还要在基础模型持续 OTA 时保持有效。于是本轮换一个问题：不是"这一步是否安全"，而是"**这份安全结论凭什么在别处仍然成立、由谁为它的失效付钱、以及当所有人都在优化这张证书本身时它还剩下多少真实性**"。

> 本轮核心命题：**把 J_vista 从"一次执行的安全位"升级为一份带作用域、可定价、可转移、可审计的「安全债权」（safety claim），并给出使车队级组合风险可被定价、而不被证书通胀掏空的四个充分条件——作用域覆盖、责任可归、相关性有界、审计激励相容。**

## 0. 直觉与动机

**灵感 1（商业模式 → 安全证书其实是一张未被定价的负债期权）**
直觉：工程师把 Valid(J) 当布尔真值，商业视角下它却是一份**合约**：持有者相信"在该范围内不会出这类事故"，发行者因此获得部署许可与保费折让。于是"安全"天然带有四个经济要素：(i) **谁承担残余风险**（vendor、集成商、站点运营方、最终客户）；(ii) **暴露多大**（概率 × 严重度，而非只有概率）；(iii) **如何转移/汇聚**（保险、再保险、责任上限）；(iv) **如何防止签约后的偷工减料**（道德风险）。这会引入工程论文里罕见的对手：**不是骗感知的对抗样本，而是骗证书的理性经济人。** 最危险的失效不是"机器人做错动作"，而是"证书在纸面上一直有效，真实风险被系统性外部化"。

**灵感 2（UniBot → 一套基础模型、多机体、多站点 = 一个高度相关的风险组合）**
直觉：UniBot 式的统一具身平台（一套策略/世界模型，经 OTA 服务多机体、多任务、多客户）极大摊薄了单位成本，但也把单点失效放大成**共模失效**：一次模型更新可能让整个车队的证书同时失效；一个透明物体类别可能同时骗过所有站点的几何与视觉。金融上这不是"很多独立保单"，而是**一个相关性未知的组合**。第 65 轮的证书只给边际概率，**边际概率不足以定价组合尾部**——正如只看单笔违约率无法给 CDO 定价。必须显式建模相关结构，并承认：**站点多样性带来分散化收益，共享基础模型带来尾部相依；两者在同一个平台上同时增长。**

**灵感 3（UniBot → 证书不可移植，作用域必须显式化）**
直觉：一份在 A 站点、v3.2 模型、标定 C1 下取得的 conformal 保证，搬到 B 站点、v3.3 模型、标定 C2，**交换性（exchangeability）已经不成立**，证书在数学上就是空的。工程上却常把它当"同一机器人、同一策略"直接复用。因此需要给每张证书一个**作用域签名** σ，把"可移植"从口头承诺变成可检验的偏序关系与漂移检验；并像软件 semver 一样，让一次 OTA 自动计算"哪些证书被击穿"。

**灵感 4（商业模式 → 故障归因 ≠ 责任归因）**
直觉：第 65 轮 FIR 回答"物理上哪一层坏了"；商业模式要回答"**合同上谁该赔**"。二者不重合：一次几何幻觉可能源于 vendor 的基础模型先验、集成商的标定、站点的地面反光、操作员的越权指令——**同一物理故障可被多方分摊责任**。责任需要反事实（but-for）与 Shapley 分摊，而不是 argmax 一个故障标签。更棘手的是：真实世界只能观测到"事实结果"，观测不到所有反事实组合，**责任常常不可辨识**；此时系统必须输出 `liability_ambiguous`，而不是替法律/合同擅自定责。

**灵感 5（合流 → LEDGER：Liability-Enabled Deployment Guarantee & Evidence Registry，可审计的安全资产负债闭环）**
闭环：证书作用域化（SCP）→ 作用域漂移监测（SDM）→ 责任分摊（RAL，把 FIR 的故障后验映射到多方责任单纯形）→ 车队组合定价（FVA，共模/相关结构下的 VaR/CVaR）→ 变更影响管理（CIM，UniBot OTA 的证书爆炸半径）→ 审计-保证金机制（ASB，让"如实上报"成为占优策略）→ 经济对抗认证（AIC-L，防证书通胀/挑樱桃/审计规避）→ 责任预算下的规划（CSP-L）→ 证书 J_ledger。**第 65 轮是"物理-归因"层；LEDGER 在其上增加"制度-经济"层，且严格分频：控制环 2.5ms、episode 归因 ~100ms、车队精算 分钟-天、治理审计 天-月。经济层永不下沉到实时控制环。**

**一个反直觉但关键的观察（本轮真正的"新问题"）**：把证书变成可交易资产，会**内生地制造新的失败模式**——证书通胀（Goodhart）、责任外部化（只认证容易的窄作用域）、相关性隐藏（把共模风险拆成独立保单卖出）、以及"评级套利"（好证书被搬运到它从未被验证的作用域）。因此**机制设计不是合规附件，而是安全工程的一等公民**；一个只优化 Valid(J_vista) 的平台，会比没有证书的平台更危险，因为它获得了不应得的信任。

## 1. 形式化定义（增量：定义 233–248）

- **定义 233（LEDGER 闭环与四种时间尺度）**：LEDGER=(GRIP, VISTA, SCP, SDM, RAL, FVA, CIM, ASB, AIC-L, CSP-L, J_ledger)。不变式：**经济/统计层（定价、责任、审计、OTA 影响）只在车队与治理流；实时控制环只多携带一个 scope_tag 与 claim_id，零新增学习与零经济计算。** 四尺度：控制环 ≤2.5ms（沿用 VISTA）；episode 归因 ~10–100ms；车队精算 分钟–天；治理审计 天–月。
- **定义 234（作用域 σ）**：σ=(e 机体类, s 站点/环境类, τ 任务分布, v 模型与固件版本, c 标定版本, o 运营策略)。证书 C=(σ, J_vista, E 证据束, issuer, t)。作用域是**可审计的声明**，不是元数据装饰。
- **定义 235（细化偏序与覆盖）**：σ₁⪯σ₂ 表示 σ₁ 更具体（在各维度上是 σ₂ 的子集）。部署作用域 σ_d 被证书覆盖 ⇔ σ_d⪯σ_c。覆盖关系构成偏序，支持"窄证书不能冒充满证书"的机械检查。
- **定义 236（可移植性亏损 δ_port）**：把一个在 σ_c 上标定的 conformal 分数搬到 σ_d 后，覆盖率的下界亏损。若分数分布的总变差为 ε，则覆盖 ≥1−α−ε；δ_port 的估计由 SDM 给出。δ_port>α_port 即判不可移植。
- **定义 237（作用域漂移监测 SDM）**：在 (站点×版本×标定) 粒度上做在线交换性/双样本检验（conformal p 值、MMD、分数分位数漂移），并区分 covariate shift、concept shift 与 calibration drift。检出即触发证书降级或重标定；**拒绝在原作用域之外继续引用该证书**。
- **定义 238（安全债权 SafetyClaim）**：Claim=(C, B_claim, holder, issuer)。若在作用域内发生可审计的越界/事故，持有人可向发行人的保证金索赔至 B_claim。它把"安全"从布尔位变成**带范围的有限负债**。
- **定义 239（责任矩阵与责任 Shapley）**：参与方 P={vendor 基础模型, integrator 标定, deployer 站点, operator 指令}。给定反事实损失函数 v(S)（仅 S 方尽职时的期望损失），责任向量 φ_i 取 Shapley 值，落在责任单纯形上；物理解释仍来自 VISTA 的 fault_posterior，作为 v 的输入证据。
- **定义 240（责任可辨识性与 liability_ambiguous）**：仅当所有联盟 S⊆P 的反事实结果可被识别（或可被有界估计）时，φ 才可辨识；若存在混杂/缺失反事实，报告 `liability_ambiguous` 并给出责任区间的偏序（谁至少不比谁责任小），**不得强行用 argmax 定责**。
- **定义 241（严重度与保单定价）**：每类失败有严重度分布 ℓ∼D_ℓ（人伤/物损/停机）。单张证书的上界失效率 p_fail 来自 J_vista 的联合界；精算保费 π=E[ℓ·1_fail]+λ·(CVaR_β(ℓ·1_fail)−E[·])+loading。**证书只约束 p_fail，严重度与尾部由部署方与承保方共同建模。**
- **定义 242（车队损失组合与共模结构）**：N 台机体的损失 L=Σ_i ℓ_i·1{fail_i}。用共模-特质分解：以概率 p_shock 触发共享潜变量（同版本模型缺陷、同类 OOD 物体、同一标定错误），否则近似独立；相关结构用 copula C_θ 或单因子模型刻画。**相关参数不来自证书，必须单独审计。**
- **定义 243（组合 CVaR 与相关性审计）**：FleetRisk_β=CVaR_β(L)。证明/报告"分散化收益"与"尾部相依"的分解；相关性审计检验 p_shock、尾部相依系数与"把共模当独立卖"的行为。目标：FleetRisk_β≤R_budget，而非仅每台 ≤r。
- **定义 244（证书依赖图、安全 semver 与爆炸半径 CIM）**：节点为证书/模型/标定/站点，边为"该证书依赖该组件"。变更 Δ 的安全 semver：major=行为/架构变更→全依赖证书失效；minor=标定/参数→需 SDM 重验；patch=无语义变更。爆炸半径 ℬ(Δ)=SDM 判失效或 δ_port 超阈的证书集合。UniBot OTA 必须先算 ℬ、再做 canary/shadow 差分证书，才允许全车队推广。
- **定义 245（审计-保证金机制 ASB）**：deployer 私下观测失败，可选择如实上报或隐瞒（收益 b_hide）；审计概率 p_a，保证金 B，查实隐瞒罚 B。**如实上报不对上报者施加惩罚（只触发修复）**，否则激励反向。vendor 的过度宣称由"赔付上限 ≤ 保证金 + 事后保费调整"约束。目标是 Bayes–Nash 激励相容，而非仅"事后追责"。
- **定义 246（证书通胀与对抗性认证 AIC-L）**：经济对手 ℰ_L={挑樱桃（只认证简单作用域）, 作用域缩窄, 块重放/证据复用, 审计规避, 串谋, 相关性隐藏}。防御：**覆盖加权证书**（按部署实际作用域测度加权而非按证书数量）、随机外作用域审计、证据新鲜度与不可重放、相关性披露义务。证书价值定义为"覆盖质量"，不是"Valid 比例"。
- **定义 247（责任预算下的规划 CSP-L 与 J_ledger）**：CSP-V 的块边代价增 λ_L·(ΔCVaR_β 的边际贡献) 与硬约束 FleetRisk_β≤R_budget；同任务下优先选择"降低组合尾部"而非仅"降低单步力残差"的技能。J_ledger=(J_vista, scope σ, δ_port, claim=(B_claim,issuer,holder), liability φ 或 ambiguous, severity 模型版本, portfolio_id, semver, audit_trail, aic_l_ver)。
- **定义 248（LEDGER 闭环算子）**：治理/车队流 [证书注册→SCP 作用域校验→SDM 漂移→RAL 责任分摊→FVA 组合定价→CIM 变更影响→ASB 审计→AIC-L 对抗认证]；部署流 [读取有效证书集→CSP-L 责任预算规划→VISTA 执行→回填证据束→触发漂移/责任更新]。**实时控制环对 LEDGER 完全不可见，只透传 scope_tag/claim_id。**

## 2. 关键算法骨架

```python
# SCP + SDM：证书能否被这台机体、这个站点、这个版本引用
def cert_valid_for(claim, sigma_d):
    if not (sigma_d <= claim.scope):                 # 定义 235 的偏序覆盖
        return False, 'scope_not_covered'
    drift = sdm.test(claim.scope, sigma_d, alpha_drift)   # conformal p 值 + MMD
    if drift.p_value < alpha_drift:
        return False, f'scope_drift:{drift.kind}'
    return drift.delta_port <= alpha_port, 'ok'

# RAL：故障后验 → 多方责任（不可辨识就说不清）
def responsibility(fault_post, parties, cf_model, observed):
    if not cf_model.identifiable(parties):
        return 'liability_ambiguous', cf_model.partial_order(parties)
    v = {S: cf_model.expected_loss(only_diligent=S, fault_post=fault_post)
         for S in subsets(parties)}
    return shapley(v, parties), 'identified'

# FVA：不是 sum of per-unit，而是组合尾部
def fleet_risk(claims, N, copula, p_shock, beta):
    marginals = [claim.p_fail for claim in claims]
    sims = [sample_loss(copula, marginals, p_shock, N) for _ in range(n_sim)]
    return cvar(sims, beta)                          # 与 R_budget 比较

# CIM：一次 OTA 会击穿哪些证书
def change_impact(delta, dep_graph):
    radius = dep_graph.descendants(delta.component)
    affected = [c for c in radius if sdm.fails_after(c, delta) or
                delta.semver == 'major']
    return affected, revalidate_plan(affected)       # canary/shadow 后才能推广

# ASB：让如实上报成为占优策略
def audit_mechanism(p_a, B, b_hide):
    assert p_a * B >= b_hide                        # 定义 245 的激励相容条件
    return 'truthful_reporting_is_dominant'
```

## 3. 保证概要与推导要点（完整推导见产物区）

- **引理 9（作用域覆盖的可移植性）**：若 σ_d⪯σ_c 且标定与部署分数分布总变差 ≤ε，则 conformal 覆盖 ≥1−α−ε；SDM 以 n=O(ε⁻²log(1/δ)) 样本可检出 ε 级漂移。故"证书可移植"是可检验命题，而非默认假设；δ_port>α_port 时必须重标定。
- **引理 10（责任的（不）可辨识性）**：责任 Shapley 可辨识 ⇔ 所有联盟的反事实损失可识别；仅观测事实结果时最多得到责任偏序。故 RAL 的正确输出包含 `liability_ambiguous` 与区间，而非伪装成确定分摊。
- **定理 9（车队组合的健全性）**：若每台部署机体的作用域被覆盖、SDM 通过、且相关性参数在审计置信集内，则 FleetRisk_β≤R_budget 以 ≥1−(α_drift+α_vis+δ_fi+α_audit) 成立（联合界）。反之，若忽略共模、把 p_shock 当 0，则组合 CVaR 在 N→∞ 时被低估 n 倍量级——**分散化不能消灭共享基础模型的尾部**。
- **定理 10（审计机制的激励相容）**：在审计独立且 B·p_a≥b_hide 时，deployer 如实上报是弱占优策略；vendor 如实宣称上界需 B_v≥(1/p_a)E[L_hidden]。关键设计是"上报失败不罚上报者"，否则机制把诚实变成自损。
- **命题（安全资产三难）**：在存在非零共模 p_shock 的 UniBot 式平台上，不可能同时做到：(i) 零重认证成本地跨作用域移植；(ii) 单张证书成本 O(1)；(iii) 单位化组合尾部随 N 消失。三者至少牺牲其一——这正是商业模式的真实约束：便宜、可搬运、尾部安全，不能全要。
- **实时性**：LEDGER 全部计算在车队/治理流；实时环只多一次 scope_tag 透传，**不改变 VISTA 的 ≤2.5ms 预算**。定价与审计延迟以分钟/天计，与闭环控制解耦。

## 5. 本轮最大风险

## 2. 形式化定义（完整版）

**定义 233（LEDGER 闭环与四时间尺度）** LEDGER 是 VISTA 之上的"制度-经济"层：在 GRIP/VISTA 的物理-归因保证之上，挂载 SCP（作用域）、SDM（漂移）、RAL（责任）、FVA（组合定价）、CIM（变更影响）、ASB（审计机制）、AIC-L（经济对抗）、CSP-L（责任预算规划），并把 J_vista 升级为 J_ledger。不变式：**所有定价、责任、审计、OTA 影响与统计检验都发生在车队流（分钟–天）与治理流（天–月）；episode 归因仍在语义流（~10–100ms）；实时控制环（≤2.5ms）只透传 scope_tag/claim_id，零新增学习写操作、零经济计算。** 由此避免"把保险精算塞进 1kHz 控制环"这一常见但致命的架构错误。

**定义 234（作用域 σ）** σ=(e,s,τ,v,c,o)：e 机体类（自由度、传感器配置、执行器），s 站点/环境类（光照、地面材质、透明物比例、人流），τ 任务分布，v 模型与固件版本，c 标定版本，o 运营策略（速度上限、接近速度、人工接管规则）。证书 C=(σ,J_vista,E,issuer,t)，E 为可复现证据束（标定记录、conformal 标定集哈希、故障注入日志、AIC 版本）。作用域必须是**可审计的声明**，且任何维度变更都可能使证书失效。

**定义 235（细化偏序与覆盖）** 在每一维度取子集关系并逐维合取，得偏序 σ₁⪯σ₂（σ₁ 更具体）。部署作用域 σ_d 被证书 C 覆盖 ⇔ σ_d⪯σ_c。偏序使"窄证书不得冒充满证书""A 站点证书不得覆盖 B 站点"成为可机械执行的检查，而不是文档里的免责声明。

**定义 236（可移植性亏损 δ_port）** 设标定分布与部署分布的 conformal 非一致性分数总变差为 ε。对任意可测集，覆盖率的损失不超过 ε，故 P[e≤q]≥1−α−ε；定义 δ_port=ε̂ 为其估计。若 δ_port>α_port，判定该证书在 σ_d 上不可移植，必须重标定。δ_port 是"这张证书搬家后打了多少折"的定量说法。

**定义 237（作用域漂移监测 SDM）** 在 (站点×版本×标定) 粒度维护分数分布，做三类检验：(i) covariate shift：输入分布 MMD/双样本检验；(ii) concept shift：残差-输入条件分布漂移；(iii) calibration drift：分数分位数漂移与覆盖经验值。用 conformal p 值给分布无关判据，n=O(ε⁻²log(1/δ)) 样本可检出 ε 级漂移。检出即把对应证书标 `drifted`，进入重标定；**不允许在原作用域外继续引用**。

**定义 238（安全债权 SafetyClaim）** Claim=(C,B_claim,holder,issuer)。若在作用域 σ 内发生可审计的越界/事故（由独立审计或 AIC-L 证据确认），持有人可向发行人索赔至 B_claim；发行人以保证金与保费调整承担。这把"安全"从布尔位变成**带范围、带上限的有限负债**，从而可定价、可转移；也正因此，它可被滥用（见定义 246）。

**定义 239（责任矩阵与责任 Shapley）** 参与方 P={vendor 基础模型, integrator 标定, deployer 站点, operator 指令}。定义联盟博弈 v(S)=仅 S 方尽职（其余回到最低标准）时的期望损失；责任分摊 φ_i 取 Shapley 值：
φ_i=Σ_{S⊆P\{i}} |S|!(|P|−|S|−1)!/|P|! · [v(S∪{i})−v(S)]。
VISTA 的 fault_posterior 作为 v 的证据输入（例如 H_force→integrator 标定权重大，H_policy→vendor 模型权重大）。**注意：Shapley 分摊的是"边际责任"，不是物理因果本身。**

**定义 240（责任可辨识性与 liability_ambiguous）** 反事实模型若要给出唯一 φ，需对所有 2^{|P|} 个联盟估计 v(S)。真实部署通常只观测事实结果，存在混杂与缺失反事实；此时最多识别出责任偏序（某些方之间的责任下界比较）。RAL 因此输出二选一：`('identified', φ)` 或 `('liability_ambiguous', partial_order, φ_interval)`。**严禁用 argmax 故障标签冒充定责**——这是把技术结论偷偷升级为法律结论。

**定义 241（严重度与保单定价）** 每类失败有严重度分布 D_ℓ（人伤、物损、停机时间）。J_vista 的联合界只给 p_fail 上界；严重度由部署方与承保方独立建模（不来自机器人证书，避免"自己给自己定损失"）。保费 π=E[ℓ·1_f]+λ(CVaR_β(ℓ·1_f)−E[ℓ·1_f])+loading，λ 为风险厌恶系数。定价的输入因此是 (p_fail^cert, D_ℓ, 相关结构)，三者来源分离、可交叉审计。

**定义 242（车队损失组合与共模结构）** N 台机体的损失 L=Σ_i ℓ_i·1{fail_i}。把失效拆为共模与特质：
1{fail_i}=1{common shock} ∨ 1{idiosyncratic_i}，
其中共模事件以概率 p_shock 触发（同一模型版本缺陷、同类透明/对抗物体、同一标定错误、同一次 OTA），特质事件近似独立，联合相关结构用 copula C_θ 或单因子模型。**关键：p_shock 与 C_θ 不来自任何单张证书，必须由跨站点审计单独估计；否则 N 张相关保单会被误当作 N 张独立保单卖出。**

**定义 243（组合 CVaR 与相关性审计）** FleetRisk_β=CVaR_β(L)。报告两项分解：(i) 分散化收益（特质部分随 N 下降）；(ii) 尾部相依（共模部分不随 N 下降）。相关性审计检验：p_shock 估计是否被系统性压低、尾部相依系数是否与宣称一致、是否把共模风险拆分成独立证书售卖。硬约束 FleetRisk_β≤R_budget；违反时触发组合层降级（限速、限任务、强制分批上线），而不是逐台加一点保守裕度。

**定义 244（证书依赖图、安全 semver 与爆炸半径 CIM）** 依赖图节点为证书、模型、标定、站点；边为"该证书依赖该组件"。变更 Δ 的 semver：major=行为/架构变更（新基础模型）→所有下游证书失效；minor=标定/参数更新→SDM 重验；patch=无语义变更→仅记录。爆炸半径 ℬ(Δ)={C : C 依赖 Δ 且 (semver=major ∨ SDM 判失效 ∨ δ_port>α_port)}。**UniBot OTA 流程强制为：先算 ℬ → shadow/canary 差分证书 → 只有当组合 FarmRisk 仍在预算内才允许全量推广。** 这条把"一次更新全车队静默失效"变成可拦截事件。

**定义 245（审计-保证金机制 ASB）** deployer 私下观测失败，可如实上报或隐瞒；隐瞒带来 b_hide（避免停机/索赔/声誉损失），审计概率 p_a，查实隐瞒罚 B。核心设计：
- **如实上报不对上报者施加惩罚**，只触发修复与保费重估（否则诚实变成自损，机制反过来奖励隐瞒）；
- 隐瞒的期望损失 p_a·B 必须 ≥ b_hide，使如实上报弱占优；
- vendor 的过度宣称由 B_v ≥ (1/p_a)E[L_hidden] 约束。
这是标准的机制设计，但必须写进安全工程：**一个没有审计的证书体系，等价于一个鼓励撒谎的证书体系。**

**定义 246（证书通胀与对抗性认证 AIC-L）** 经济对手 ℰ_L 包括：挑樱桃（只在简单作用域取证）、作用域缩窄（把证书声明得极窄以抬高 Valid 率）、证据复用/块重放（旧证据包装成新证据）、审计规避（在审计窗口外运行）、串谋（deployer 与审计方合谋）、相关性隐藏（把共模当独立）。防御：
1. **覆盖加权证书** cov_ratio：按实际部署作用域测度加权，而非按"证书数量/Valid 比例"；
2. **随机外作用域审计**：对声明之外但实际发生的部署采样，专打作用域缩窄；
3. **证据新鲜度与不可重放**：时间戳、随机挑战、硬件根信任；
4. **相关性披露义务**：p_shock 与 C_θ 的估计纳入审计，隐瞒按虚假陈述处理；
5. 证书价值定义为"覆盖质量×可审计性"，不是"通过率"。
**Goodhart 的形式化**：若优化目标是 Valid 比例而真实目标是损失，则存在对手把 Valid↑ 同时使真实损失↑；只有当证书按覆盖测度加权并配合外作用域随机审计，两者才近似同向。

**定义 247（责任预算下的规划 CSP-L 与 J_ledger）** CSP-V 的块边代价增 λ_L·ΔCVaR_β（该决策对组合尾部的边际贡献）与硬约束 FleetRisk_β≤R_budget。同等成功率下，优先选择"降低组合尾部/降低共模暴露"的技能（例如避免所有机体同时走同一窄通道），而非只压低单步力残差。J_ledger=(J_vista, σ, δ_port, Claim, φ 或 `liability_ambiguous`, D_ℓ 版本, portfolio_id, semver, audit_trail, aic_l_ver)。验证规则：
Valid(J_ledger) ⇔ Valid(J_vista) ∧ σ_d⪯σ ∧ δ_port≤α_port ∧ (φ 已识别 ∨ 明确 `liability_ambiguous`) ∧ semver 与依赖图一致 ∧ audit_trail 完整 ∧ aic_l_ver 为当前版本。

**定义 248（LEDGER 闭环算子）** 治理/车队流：证书注册→SCP 作用域校验→SDM 漂移监测→RAL 责任分摊→FVA 组合定价→CIM 变更影响→ASB 审计→AIC-L 对抗认证→证书状态机（valid/drifted/revoked/ambiguous）。部署流：读取有效证书集→CSP-L 责任预算规划→VISTA 执行→回填证据束→触发漂移/责任/组合更新。不变式：**实时控制环对 LEDGER 不可见，只透传 scope_tag/claim_id；证书状态变化只通过低频配置热更新影响控制环，不进入控制律计算。**

### IP-224/225 SCP + SDM（作用域与漂移）

```python
class ScopeClaim:
    """作用域签名 + 覆盖检查；经济层的入口闸门。"""
    def __init__(self, e, s, tau, v, c, o, j_vista, evidence, issuer, t):
        self.scope = {'e': e, 's': s, 'tau': tau, 'v': v, 'c': c, 'o': o}
        self.j_vista, self.evidence, self.issuer, self.t = j_vista, evidence, issuer, t
        self.state = 'valid'

    def covers(self, sigma_d):                       # 定义 235：逐维子集
        return all(set(sigma_d[k]) <= set(self.scope[k]) for k in self.scope)

    def portability(self, sigma_d, sdm, alpha_port=0.05):
        if not self.covers(sigma_d):
            return False, {'reason': 'scope_not_covered'}
        drift = sdm.test(self.scope, sigma_d)        # conformal p + MMD
        if drift.p_value < drift.alpha:
            self.state = 'drifted'
            return False, {'reason': f'drift:{drift.kind}', 'delta_port': drift.delta}
        ok = drift.delta <= alpha_port
        self.state = 'valid' if ok else 'needs_recalibration'
        return ok, {'delta_port': drift.delta, 'p_value': drift.p_value}


class ScopeDriftMonitor:
    """站点×版本×标定粒度；只做统计检验，不碰控制。"""
    def test(self, scope_c, scope_d, n_boot=200):
        sc = self.scores[(scope_c['s'], scope_c['v'], scope_c['c'])]
        sd = self.scores[(scope_d['s'], scope_d['v'], scope_d['c'])]
        p_cov = conformal_pvalue(sc, sd)              # 交换性检验
        kind = ('covariate' if self._mmd(sc.X, sd.X) > self.tau_x else
                'concept' if self._residual_drift(sc, sd) > self.tau_r else
                'calibration')
        return Drift(p_value=p_cov, delta=total_variation(sc.s, sd.s), kind=kind)
```

### IP-226 RAL（故障后验 → 责任分摊）

```python
class ResponsibilityAttributor:
    PARTIES = ('vendor', 'integrator', 'deployer', 'operator')

    def attribute(self, fault_post, cf_model):
        if not cf_model.identifiable(self.PARTIES):
            # 不假装定责：给区间与偏序
            return {'status': 'liability_ambiguous',
                    'order': cf_model.partial_order(self.PARTIES),
                    'interval': cf_model.shapley_interval(self.PARTIES)}
        v = {}
        for S in powerset(self.PARTIES):              # |P|=4 → 16 个联盟
            v[frozenset(S)] = cf_model.expected_loss(only_diligent=S,
                                                     fault_post=fault_post)
        phi = shapley(v, self.PARTIES)
        return {'status': 'identified', 'phi': phi, 'sum': sum(phi.values())}

    def map_fault_to_cf(self, h_star):
        # 物理归因只作反事实模型的先验，不直接定责
        return {'H_geo': {'vendor': .4, 'integrator': .3, 'deployer': .3},
                'H_force': {'integrator': .7, 'vendor': .2, 'operator': .1},
                'H_model': {'vendor': .8, 'integrator': .1, 'deployer': .1},
                'H_policy': {'vendor': .6, 'operator': .4},
```

### IP-227 FVA（车队组合尾部）

```python
class FleetValuation:
    """共模-特质分解；拒绝把相关保单当独立保单。"""
    def risk(self, claims, N, p_shock, copula, beta=0.995, n_sim=20000):
        losses = np.zeros(n_sim)
        for claim in claims:
            p = claim.j_vista.p_fail_upper
            common = np.random.rand(n_sim) < p_shock       # 共享冲击
            idio = copula.sample_u(n_sim) < p
            failed = common | idio
            losses += failed * claim.severity.sample(n_sim)
        return {'cvar': cvar(losses, beta), 'var': var(losses, beta),
                'diversification': self._div(losses, claims, N),
                'tail_dependence': self._tail_dep(losses, claims)}

    def audit_correlation(self, reported, empirical):
        # 相关性披露审计：谎报 p_shock/尾部相依 = 虚假陈述
        gap = abs(reported['p_shock'] - empirical['p_shock'])
        return {'ok': gap <= self.tau_corr,
                'flag': None if gap <= self.tau_corr else 'correlation_misreport'}
```

```python
class AuditBondMechanism:
    """机制设计：让如实上报成为弱占优。"""
    def __init__(self, p_a, B, b_hide, B_vendor):
        self.p_a, self.B, self.b_hide, self.B_vendor = p_a, B, b_hide, B_vendor

    def incentive_compatible(self):

        if (not report.revealed) and audit_result.confirmed:
            return {'penalty': self.B, 'remediation': 'triggered'}
        return {'penalty': 0.0, 'remediation': 'none'}
```

### IP-231/232 CSP-L + J_ledger（责任预算下的规划与证书）

```python
def plan_under_liability_budget(tau_candidates, fleet, R_budget, lam_L):
    best = None
    for tau in tau_candidates:
        risk = fleet.marginal_cvar(tau)                # ΔFleetRisk_β
        cost = tau.exec_loss + lam_L * risk
        if fleet.risk_with(tau) <= R_budget and tau.k_star >= 1:
            if best is None or cost < best[0]:
                best = (cost, tau)
    return None if best is None else best[1]           # None → safe_idle + 组合降级


def build_j_ledger(cert_exec, j_vista, scope, delta_port, claim, resp,

        'liability': resp,                               # phi 或 liability_ambiguous
        'severity_model': severity_ver, 'portfolio_id': portfolio_id,
        'semver': semver, 'audit_trail': audit_trail,
        'aic_l_ver': AIC_L_VERSION,
        'valid': (j_vista['valid'] and scope_covered(scope)
                  and delta_port <= ALPHA_PORT
```

### IP-233 LEDGER 闭环算子（整合，四时间尺度）

```python
def LEDGER_cycle(fleet, registry, obs, delta=None):
    # ———— 治理/车队流（分钟–天；不在控制环）————
    for C in registry.valid_claims():
        C.state, info = C.portability(fleet.sigma_d, fleet.sdm)
        if C.state != 'valid':
            fleet.degrade(C.scope)                   # 组合层降级
    if delta is not None:                            # UniBot OTA
        affected, plan = change_impact(delta, registry.dep_graph, fleet.sdm)
        fleet.revalidate(plan)                       # canary/shadow 通过才推广
    resp = fleet.ral.attribute(fleet.last_fault_post, fleet.cf_model)
    fr = fleet.fva.risk(registry.valid_claims(), fleet.N, fleet.p_shock, fleet.copula)
    if fr['cvar'] > fleet.R_budget:
        fleet.restrict(limit_speed=True, batch_rollout=True)
    audit = fleet.asb.audit_sample()
    registry.update(fleet.ral, fr, resp, audit)

    # ———— episode 流（~10–100ms）————
    A = fleet.vista.propose(obs)
    tau = plan_under_liability_budget(A, fleet, fleet.R_budget, fleet.lam_L)
    if tau is None:
        return safe_idle(fleet)                      # 责任预算不可行
    k_star = fleet.vista.csc.certified_prefix(tau.A, fleet.last_post,
                                              fleet.m, fleet.alpha_chunk)
    # ———— 实时控制环（≤2.5ms，对 LEDGER 不可见）————
    cert_exec = fleet.vista.execute_prefix(tau, k_star, obs)
    j_ledger = build_j_ledger(cert_exec, fleet.last_j_vista, fleet.sigma_d,
                              fleet.last_delta_port, fleet.claim, resp,
                              fleet.severity_ver, fleet.portfolio_id,
                              fleet.semver, fleet.audit_trail)
    return j_ledger, cert_exec
```

## 4. 推导

**引理 9（作用域覆盖的可移植性）** 设标定分数 S_c 与部署分数 S_d 的分布总变差 ≤ε。对任意阈值 q，|P(S_c≤q)−P(S_d≤q)|≤ε；由 conformal 覆盖 P(S_c≤q_α)≥1−α，得 P(S_d≤q_α)≥1−α−ε。故 δ_port≤ε 时证书在 σ_d 上仍以 ≥1−α−ε 覆盖。检测侧：以 MMD/双样本检验区分 ε 级漂移所需样本 n=O(ε⁻²log(1/δ))（标准双样本下界）。因此"证书可跨作用域复用"是一个**可检验命题**，不是默认假设；当 δ_port>α_port 时唯一正确动作是重标定或拒绝引用。∎

**引理 10（责任的（不）可辨识性）** Shapley 值 φ 是 2^{|P|} 个联盟值 v(S) 的线性泛函，且该线性映射满秩（|P|≤4 时可直接验证）。故 φ 可辨识 ⇔ 所有 v(S) 可识别。仅观测事实结果时，未观测联盟的反事实损失只能给有界区间，因此最多识别责任偏序。特别地，若某参与方从不单独行动（其边际贡献在所有联盟中同号同幅），则其与另一方的责任不可分——这正是"不可辨识"，而非"责任为零"。RAL 输出 `liability_ambiguous` 是数学上正确的结论。∎

**定理 9（车队组合的健全性）** 设每台部署机体 i 的作用域被覆盖（引理 9，失败概率 ≤α_drift）、VISTA 证书成立（失败 ≤α_vis+δ_fi）、审计机制按规定运行（失败 ≤α_audit），且 FVA 的相关参数 (p_shock,C_θ) 落在审计置信集内。则对组合损失 L=Σℓ_i·1{fail_i}，有
P[FleetRisk_β(L) ≤ R_budget] ≥ 1−(α_drift+α_vis+δ_fi+α_audit)。
证明：对"证书覆盖失败∪VISTA 失效∪审计失效∪相关参数越界"取联合界；在补事件上，每张契约的 p_fail 上界与相关结构均有效，FVA 直接以这些上界与 C_θ 计算 CVaR，故预算成立。反向结论：若把 p_shock 误设为 0，则组合损失尾部被低估。取单因子模型，当 p_shock=p₀>0 时，任意 N 下 CVaR_β(L)/N ≥ ℓ̄·p₀·c_β>0（c_β 为单因子尾部的常数），即**单位化组合尾部不随 N→0**；把 p_shock 当 0 会把它估成 O(1/√N)——高估分散化收益，恰是相关违约被系统性低估的机制。∎

**定理 10（审计机制的激励相容）** 设 deployer 隐瞒的确定收益为 b_hide，审计独立且概率 p_a，查实罚 B；如实上报不罚。若 p_a·B≥b_hide，则对任意 b_hide，如实上报的期望损失 ≤ 隐瞒的期望损失（0 ≤ (1−p_a)b_hide − p_a(B−b_hide) 在所设条件下成立），故如实上报弱占优。vendor 侧：若其宣称上界的真实超出部分期望损失为 E[L_hidden]，保证金 B_v 在查实时被扣，则其诚实宣称的充要条件为 p_a·B_v ≥ E[L_hidden]。**关键是"上报失败不罚上报者"**：若上报也罚，则诚实相对隐瞒的收益变为负，机制反向奖励沉默。∎

**命题（安全资产三难）** 在 p_shock=p₀>0 的 UniBot 式共享基础模型平台上，下列三者不可同时成立：
(i) 跨作用域零重认证移植（δ_port=0 对所有 σ_d 成立）；
(ii) 单张证书成本 O(1)（与作用域数量无关）；
(iii) 单位化组合尾部随 N 消失（FleetRisk_β/N→0）。
证明要点：由引理 9，跨作用域移植要求 ε=0，即标定与部署分数分布完全相同；而 UniBot 的多站点、多机体、持续 OTA 使 ε>0（否则无需版本/标定/站点维度），故 (i) 与真实异构性矛盾，除非对每个作用域重标定，成本随作用域数增长，破坏 (ii)。若坚持 (ii) 而用不重标定的证书，则由定理 9 的反向部分，p_shock>0 使 (iii) 失败。故至少牺牲其一。**这就是商业模式的真实约束：便宜、可搬运、尾部安全，不能全要；否定它的商业计划只是在把风险转移到看不见的地方。** ∎

**命题（覆盖加权对抗 Goodhart）** 设真实目标为期望损失 L，代理目标为 Valid 比例 v。对手可将 v 提高到 1 而 L 不降（缩窄作用域至空集附近）。若代理改为覆盖加权 cov_ratio=∫_{σ∈部署支撑} 1[valid(σ)] dμ(σ)/μ(部署支撑)，并配合对外作用域随机审计（每次审计以概率 p_o 命中声明外部署），则对手提升 cov_ratio 必须实际扩大有效覆盖或承受审计罚；在最优点处，代理与真实损失同向的充分条件为 μ(声明外部署)/μ(部署支撑) ≤ (p_o·B_audit)/(∂L/∂coverage)。∎

## 7. 已知风险

**一句话**：LEDGER 把证书变成可定价、可交易的资产，也就把它变成了一个**优化目标**——当平台、部署方与承保方都在优化这张证书而非真实伤害时，最理性的行为是缩窄作用域、挑樱桃、隐藏共模相关，于是**证书越"健全"，真实风险越被外部化**；而 UniBot 的共享基础模型恰好保证这些被隐藏的相关性会在同一次 OOD 事件里一起兑现，使"安全资产组合"在最需要赔付的尾部同时违约——**这是本轮全部定价与激励相容论证共同依赖、也最容易被商业模式本身反向利用的隐藏假设。**

**次级风险与缓解**：
1. **机制设计假设过强**（审计独立、风险中性、无合谋）：真实审计可能被俘获、承保方与被保方串谋。缓解：多方独立审计、审计方轮换、审计结果上链存证、把 AIC-L 的合谋情景纳入认证。**但无法根除，只能提高合谋成本。**
2. **相关结构不可辨识**：p_shock 与 copula 在有限站点/有限历史下估计不稳，尾部外推最不可靠。缓解：给相关性区间而非点估计、用最坏相关做保守定价、限制组合规模、强制分批上线（牺牲规模换尾部可控）。
3. **责任 Shapley 的反事实模型本身可被操纵**：谁定义 v(S) 谁就在分配责任。缓解：反事实模型开源可审计、多方共同拟合、责任区间而非单点、保留 `liability_ambiguous` 作为合法输出。
4. **证书通胀的长期漂移**：短期内覆盖加权有效，长期对手会学习审计分布。缓解：随机化审计策略、外作用域审计、对"作用域异常变窄"设告警、周期性对抗重认证。
5. **SDM 在无标签在线场景下检出慢**：concept shift 无标签时难以区分。缓解：主动标注预算、保守阈值、漂移即停用而非自适应。
6. **经济层延迟与安全层解耦带来的窗口风险**：证书已 drifted 但控制环尚未收到降级配置。缓解：证书状态热更新有界延迟契约、本地缓存失效策略、fail-safe 默认拒绝。
7. **保费/保证金把安全投资挤出**：小部署方付不起 B_v，被迫接受更差条款或退出。缓解：分级保证金、再保险池、公共安全基础设施；但这会把风险社会化——本身又是一个治理问题。
8. **过度形式化的风险**：用物理级严谨度去建模人类制度，可能得到"数学上漂亮、制度上幼稚"的结论。缓解：把经济层明确标为**决策支持**而非自动定责；最终责任仍需人类/法律程序；所有输出保留可争议的审计链。

**结论**：第 65 轮把"可证伪"升级为"可归因"；第 66 轮承认**归因只解决技术真值，不解决制度信任**，于是把安全证书做成带作用域、可定价、可审计的债权，并用四个显式条件把"可交易"约束在"仍可证伪"之内。最大的危险不是算错一张证书，而是**证书体系自己变成了被优化的目标**——因此 LEDGER 的每个组件都必须保留一个"拒绝给出结论"的出口（scope_not_covered / drifted / liability_ambiguous / correlation_misreport / budget_violation），这比任何漂亮的定价公式都更重要。
