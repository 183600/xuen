### 第 6 轮灵感驱动研究记录（新循环第 1 轮，承接 CADVS-v5）

**灵感词**：分层规划、开源软件

**继承关系**：第 5 轮 CADVS-v5（IP-493~496）把提议器升级为条件流匹配（FMPP）、记忆升级为嵌入+固化（LMEM-v2）、人因升级为情感调制（FAMK），并用「定理 6 证书不变性」把框架推广为「任意生成器 + 认证边界」（CGE），执行集 Exec_CADVS-v5 ⊆ Exec_CADVS-v4 ⊆ … ⊆ Exec_v29。v5 有两条未被处理的结构性边界：(a) 证书是**扁平的**——它只认证单条轨迹/单个技能，无法认证「任务→子任务→技能→运动基元→控制设定值」跨抽象层的组合，父层假设在子层不可见，兄弟子计划的资源耦合（共享工作空间/物体/力预算）不被检查；(b) 整个信任基是**封闭、不可复现、无来源证明**的——门代码、阈值、模型、数据混在一个不可独立审计的黑箱里，开源既能带来大规模红队与可审计性，也会引入供应链攻击（恶意补丁、依赖混淆、投毒语料、静默削弱门）。本轮不推翻 v5，而把两个灵感词统一为主题「开放分层认证栈」（Open Layered Certification Stack, OLCS），形成 CADVS-v6（IP-497~500）。本轮自律延续 v5：**硬门数量不增**（七门与 τ^5 冻结），新增能力全部走「层契约封装 + 可复现溯源 + 贡献差分认证」三条非侵入路径，执行集升级为 Exec_CADVS-v6 ⊆ Exec_CADVS-v5。

**直觉与动机**：

1. **分层规划 → 证书必须能跨抽象层抬升，但抬升绝不能凭空制造边际**。直觉：真实系统不是一张平坦规则表，而是一棵计划树；把一堆各自通过底层门的技能拼成任务，并不能推出任务级安全，因为父层的假设（工作空间、时序、资源）可能在子层不可见，子层的保证也可能不蕴含父层不变式。严谨化：引入**分层契约格（HCL）**。计划是带层号的 DAG，节点 v 携带契约 K_v=(A_v,G_v,E_v,R_v,sig)：假设集、保证边际、末态集、资源足迹、门签名。层内用守卫组合 ∘（仅当 E_child^Δ⊆A_child 时有定义），跨层用**抬升算子 ↑**：G_parent := min( min_{c∈children} G_c , m_parent^couple )，其中 m_parent^couple 只由父层耦合检查（兄弟资源非干涉 NI + 时序/离散化间隙）给出。由于取 min，抬升**不放大**任何边际（G_parent ≤ min_c G_c）。**定理 15（抬升不增信）**：抽象只能丢信息、不能造边际；父层执行集含于子层执行集的投影。这是「分层规划」给证书体系带来的核心约束。

2. **开源软件 → 安全栈本身必须可复现、可溯源、可分叉而不静默降级**。直觉：闭源认证只能「相信厂商」，开源认证可以「自己重算」；但开源也把门实现、阈值、模型暴露给攻击者。严谨化：引入**开放来源与可复现认证核（OPRC）**。每次认证产出**证书物料清单（CBOM）**：门代码哈希、阈值 τ^4/τ^5 哈希、提议/记忆/FER 模型哈希、工具链与硬件指纹、数据清单哈希、验证器哈希。认证在给定 CBOM 下**确定性可重放**（数值误差 ε 内一致），于是任意第三方可裁决两方证书分歧。**最小信任基（TCB）**只含门谓词 kc_i + 验证器 + 签名根；提议器、记忆、FER 一律移出 TCB——由 v5 定理 6（证书不变性），它们本就不影响执行边界，只能影响完备性与时延。**分叉语义**：证书身份承诺 CBOM 哈希，任何门/阈值改动都产生新 CBOM，旧证书不能跨分叉继承（fail-closed），开源分叉因此无法静默削弱安全。

3. **开源贡献既是最大红队，也是最大攻击面 → 用差分认证做贡献门控**。直觉：开放 PR 能引入全世界的对抗测试，也能引入一个「看起来只改注释」的恶意补丁把 `>=` 改成 `>`。严谨化：引入**开源贡献门控（OCG）**。贡献 c（门补丁/阈值提案/策略更新/记忆语料）被接受当且仅当 Acc(c) = 来源签名 ∧ 可复现构建 ∧ **差分认证 ΔExec(c)⊆∅** ∧ 红队回归 ∧ 人工评审 quorum。差分认证是关键结构性防御：门/阈值补丁若使执行集变大则直接拒绝；策略/记忆更新由证书不变性天然不改 Exec，但仍需来源与红队。威胁模型显式覆盖：typosquatting、依赖混淆、被攻陷维护者、投毒记忆、许可证洗白；用可复现 bug 报告 + Sybil 抗性加权维护社区红队账本。

**关键洞见**：v5 问「提议任意时证书边界是否不变」；v6 问「当边界由许多开放、分层、第三方模块拼装时，信任如何传播而不被放大、也不被静默削弱」。答案是一条三段式：**分层契约抬升（只减不增） + 可复现溯源（可裁决） + 贡献差分认证（只缩不涨）**。七硬门 kc_evidence_forged_v5 与 τ^5 原样冻结；新增的是抬升算子 ↑、组合算子 ∘、CBOM 承诺、差分证书 ΔExec 与最小 TCB。原子执行集 Exec_v6 ⊆ Exec_v5，计划层执行集 PlanExec_v6 = Closure_{∘,↑}(Exec_v6)。

**形式化目标（增量）**：
1. HCL：节点契约 K_v=(ℓ_v,A_v,G_v,E_v,R_v,sig)；层内组合 ∘、跨层抬升 ↑、兄弟资源非干涉 NI；G_parent=min(min_c G_c, m_couple)。
2. OPRC：CBOM = (h(gates), h(τ), h(models), h(toolchain), h(hardware), h(data_manifest), h(verifier))；可复现关系 Cert(B,x) ≡_ε Cert(B,x)；TCB = {kc_i, verifier, sig_root}。
3. OCG：Acc(c) = Prov(c) ∧ Repro(c) ∧ [Exec_{t+1} ⊆ Exec_t] ∧ Red(c) ∧ Quorum(c)；分叉身份 = CBOM 哈希。
4. 定理 14（分层组合可靠性）、定理 15（抬升不增信）、定理 16（可复现裁决）、定理 17（供应链/分叉单调性）、定理 18（TCB 最小化保持证书不变性）；引理 46（抽象间隙界）。
5. EFA-v6：select_plan = 逐叶七门 → HCL 抬升/组合 → CBOM 校验 → TCB 检查 → 差分认证；原子 Exec_v6 ⊆ Exec_v5。

**本轮最大风险**：**契约充分性不可证**——分层组合的可靠性完全依赖人手写的 assume-guarantee 契约；若父层假设漏掉一个耦合项（共享物体、力预算、时序），则每个子节点都能通过各自的门、证书也完全可复现，而父层计划实质不安全。开源与可复现只能验证「计算与来源」，不能验证「契约是否充分」；社区评审降低但无法证明充分性，于是系统可能稳定地、可复现地铸出一张错误的证书。

## 2. 关键算法骨架

### IP-497 HCL：分层契约格（规划/准入时域，离线或 10 Hz）

```python
@dataclass(frozen=True)
class Contract:
    """七硬门上的分层 assume-guarantee 契约。门集合不变，契约只是门的时域/层级封装。
    红线：sig 必须等于 v5 冻结门签名 + τ^5 哈希，任何门改动使契约失效"""
    layer: int                      # ℓ：0 任务 … 4 控制
    A: Region                       # 假设集
    G: Callable[[State], float]     # 保证边际 G(s)=min_i inf m_i ≥ 0
    E: Callable[[State], Region]    # 末态集
    R: ResourceFootprint            # 资源足迹（空间/物体/力预算）
    sig: tuple                      # 冻结门签名 + 阈值哈希

def compose(k1: Contract, k2: Contract, delta: float) -> Contract | None:
    """层内 K2∘K1：守卫 E1^Δ(A1) ⊆ A2；不满足则拒绝（fail-closed）"""
    if k1.layer != k2.layer or k1.sig != k2.sig:
        return None
    if not subset(inflate(k1.E_of(k1.A), delta), k2.A):
        return None
    return Contract(layer=k1.layer, A=k1.A,
                    G=lambda s: min(k1.G(s), inf_over(k2.G, inflate(k1.E_of(s), delta))),
                    E=lambda s: union_over(k2.E_of, inflate(k1.E_of(s), delta)),
                    R=k1.R.union(k2.R), sig=k1.sig)

def lift(children: list[Contract], parent_layer: int, m_couple: float,
         delta: float) -> Contract | None:
    """跨层 ↑：父层只继承子层最弱保证，耦合项另算；取 min 故不放大边际"""
    if len({c.sig for c in children}) != 1:
        return None                                   # 门签名不一致，拒绝
    if not resource_noninterference([c.R for c in children]):
        return None                                   # 兄弟资源耦合未认证，拒绝
    A = intersection_of_assumptions(children)         # 父假设必须被子假设覆盖
    def G(s: State) -> float:
        # 关键：min ⇒ 抬升不增信（定理 15）
        return min(min(c.G(s) for c in children), m_couple)
    def E(s: State) -> Region:
        return union_all(c.E_of(s) for c in children)
    return Contract(layer=parent_layer, A=A, G=G, E=E,
                    R=union_all(c.R for c in children), sig=children[0].sig)

def certify_plan(root: Contract, s0: State, delta: float,
                 m_min: float) -> PlanCertificate:
    """按拓扑序自底向上抬升；任一层无定义或边际 < m_min → fail-closed"""
    for v in topo_order(root):
        k = v.leaf_contract if is_leaf(v) else lift(v.children, v.layer,
                                                   v.m_couple, delta)
        if k is None:
            return PlanCertificate(ok=False, reason='LIFT_OR_GUARD_FAIL')
        if k.G(s0) < m_min:
            return PlanCertificate(ok=False, reason='MARGIN_EXHAUSTED')
    return PlanCertificate(ok=True, margin=root.G(s0),
                           abstraction_gap=root.m_couple)
```

### IP-498 OPRC：开放来源与可复现认证核（离线构建 + 在线校验，O(1) 查表）

```python
@dataclass(frozen=True)
class CBOM:
    """证书物料清单：证书身份 = 全部安全相关构件的哈希。改任何一项 = 新分叉"""
    gate_code: str          # h(七门实现)
    thresholds: str         # h(τ^4, τ^5)
    models: str             # h(π_FM, LMEM, FAMK)
    toolchain: str          # h(编译器/框架版本)
    hardware: str           # h(硬件/驱动指纹)
    data_manifest: str      # h(训练/校准数据清单)
    verifier: str           # h(认证验证器)
    def hash(self) -> str:
        return sha256(join(self.gate_code, self.thresholds, self.models,
                           self.toolchain, self.hardware,
                           self.data_manifest, self.verifier))

class ReproducibleCertifier:
    """确定性认证 + 可重放 + 最小 TCB。提议/记忆/FER 不在 TCB 内（定理 18）"""
    tcb = ('gates', 'verifier', 'sig_root')      # 只有这些被信任

    def certify(self, cbom: CBOM, x: Trajectory) -> Certificate:
        assert verify_signature(cbom)             # 来源根校验
        m = [gate_margin_i(x, cbom.thresholds) for i in GATES]   # 只依赖 TCB
        return Certificate(cbom_hash=cbom.hash(), margins=m,
                           passed=all(mi >= 0 for mi in m),
                           sig=Sign_root(sha256(m)))

    def replay_equal(self, c1: Certificate, c2: Certificate) -> bool:
        # 第三方裁决：同 CBOM 必须 ≡_ε；不一致 ⇒ CBOM/硬件/验证器不一致（定理 16）
        return c1.cbom_hash == c2.cbom_hash and all(
            abs(a - b) <= EPS_NUM for a, b in zip(c1.margins, c2.margins))

    def accept_cross_fork(self, cert: Certificate, local: CBOM) -> bool:
        # 分叉语义：不同 fork_id 的证书不可互认（fail-closed）
        return cert.cbom_hash == local.hash()
```

### IP-499 OCG：开源贡献门控（PR/发布时域，离线）

```python
@dataclass
class OpenContributionGateway:
    """开放贡献 = 最大红队 + 最大攻击面。差分认证是结构性防线（定理 17）"""
    quorum_by_risk: dict = field(default_factory=lambda:
        {'doc': 1, 'policy': 2, 'memory': 2, 'gate': 4, 'threshold': 4})

    def accept(self, c: Contribution, prev: CBOM, red_baseline: RedReport) -> bool:
        if not self.provenance_ok(c):        return False   # 签名链/依赖混淆/typosquat
        if not self.reproducible_build(c):   return False   # 可复现构建
        # 差分认证：门/阈值补丁只允许缩小执行集；策略/记忆由证书不变性天然不改 Exec
        after = certify_exec_set(c, prev)
        if not exec_subset(after, certify_exec_set(None, prev)):
            return False                                   # ΔExec ⊄ ∅ → 拒绝
        if not self.redteam_ok(c, red_baseline): return False
        if not self.quorum_ok(c):            return False
        return True

    def provenance_ok(self, c) -> bool:
        # 来源 ∈ 已知维护者根；依赖名/仓库/哈希与注册表一致（反 typosquat/依赖混淆）
        return (c.sig_chain.roots_to_known_maintainer()
                and registry_matches(c.dependencies))

    def exec_subset(self, a, b) -> bool:
        # 用差分认证器在门边界网格 + 红队样本上验证 a ⊆ b（经验 + 可证界）
        return differential_verifier.prove_subset(a, b)
```

### IP-500 EFA-v6：分层选证 + 供应链校验（准入/规划时域，异步）

```python
@dataclass
class EvidenceForgingAssemblerV6:
    """EFA-v6：七门与 τ^5 冻结 + 分层认证 + CBOM/TCB + 差分认证"""
    v5: EvidenceForgingAssemblerV5
    hcl: HierarchicalContractLattice
    oprc: ReproducibleCertifier
    ocg: OpenContributionGateway

    def select_plan(self, task, s0, delta, cbom: CBOM):
        if not self.oprc.verify_signature(cbom):          # 来源根
            return False, None, 'PROVENANCE_FAIL'
        if not set(self.oprc.tcb).issubset(cbom.trusted_set()):
            return False, None, 'TCB_MISMATCH'
        plan = self.v5.fmpp.propose_plan(task, depth=5)    # 复用 v5 提议
        for leaf in leaves(plan):                          # 原子层：七门不变
            cert = self.oprc.certify(cbom, leaf.traj)
            if not cert.passed:
                return False, None, 'ATOMIC_GATE_REJECT'
        pc = self.hcl.certify_plan(plan.root, s0, delta, m_min=self.v5.m_min)
        if not pc.ok:
            return False, None, pc.reason
        # 贡献若来自外部补丁，必须已通过 OCG；否则拒绝消费其证书
        if plan.from_external and not self.ocg.accept(plan.contribution, cbom,
                                                      self.v5.red_baseline):
            return False, None, 'SUPPLY_CHAIN_REJECT'
        return True, pc, 'FORGED_OLCS'
```

### 集成流水线（v5 → v6）

```
离线/慢时域：
  开源生态：贡献 PR ──▶ OCG（来源/可复现/差分认证/红队/quorum）──▶ 合并或拒绝
  证书构建：合并后重算 CBOM ──▶ 签名 ──▶ 发布（fork_id = CBOM 哈希）
  契约编译：每技能离线计算 (A,G,E,R) 与耦合项 m_couple；门签名冻结
  记忆固化：复用 v5 LMEM-v2（只改提议器）；条目附 provenance/cbom_id

在线规划/准入（异步，秒级）：
  CBOM/TCB 校验 ──▶ FMPP.propose_plan ──▶ 逐叶七门（v5 冻结门） 
       ──▶ HCL 自底向上 ↑/∘ ──▶ 差分证书校验 ──▶ 计划证书
       ├─ 任一层失败/边际耗尽 ──▶ fail-closed 回退 v5 单层执行或拆分任务
       └─ 通过 ──▶ 消费计划证书（含 fork_id 与 CBOM 哈希）

在线控制环（1 kHz，不变）：
  每周期：EEK(kc_ee) + BCK（事件触发缓存证书）；消费冻结 τ^5
  只读 TCB 门谓词；提议/记忆/FER 全部异步，不进入控制环
```

## 3. 复杂度分析（增量更新）

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 | 实时性 |
|---|---|---|---|---|
| HCL.compose | O(|∂E|·d_S) / 次 | O(|契约|) | 每链 L 次 | 规划时域，<0.1 ms/段 |
| HCL.lift | O(|children|·|∂E|·d_S + |R|²) | O(|契约|) | 分支度 b≤8 | 规划时域，~1–5 ms/计划 |
| HCL.certify_plan | O(|V|·|∂E|·d_S) | O(|V|) | |V|≤200 | 规划时域，~2–8 ms |
| OPRC.certify | O(1) 查表 + 门评估 O(1) | O(1) | CBOM 7 项哈希 | <0.05 ms/轨迹 |
| OPRC.replay_equal | O(d_gates) | O(1) | — | <0.01 ms |
| OCG.accept | O(差分认证) | O(1) 额外 | 发布时域 | 离线，秒~分钟 |
| EFA-v6 原子门 | O(1)（复用 v5） | O(1) | — | <0.03 ms |
| 端到端在线增量 | ~0（控制环仅多 O(1) CBOM 哈希比对） | — | — | **不破坏 v5 的 P99 ~0.55 ms** |

**通信开销**：CBOM 约 0.5–1 KB（7 个哈希）；计划证书约 1–4 KB（节点边际向量 + CBOM 哈希 + 签名）；贡献审计摘要 DP 后低频上传。分层契约与 CBOM 只在规划/发布时域传输，不进控制环。

**实时性说明**：HCL/OPRC/OCG 全在规划/离线时域；控制环只多一次 O(1) 的 CBOM 哈希比对（且可缓存），因此 v6 不偿还也不恶化 v5 的实时性成果。

## 4. 正确性论证（增量更新）

### 引理 46（抽象间隙界）

**陈述**：设父节点 p 的子契约为 {K_c}，每个子契约在其假设内可靠，且耦合检查（NI + 时序/离散化）的边际为 m_p^couple。则父层实际可保证的边际与子层最弱保证之差不超过耦合间隙：G_p ≥ min_c G_c − δ_couple，其中 δ_couple = max(0, −m_p^couple) + ε_abs，ε_abs 为抽象离散化误差。**证明**：由抬升定义 G_p=min(min_c G_c, m_p^couple)；若 m_p^couple ≥ min_c G_c 则间隙为 0；否则间隙 ≤ min_c G_c − m_p^couple，再加上离散化项。∎

**诚实边界**：m_p^couple 由人手设定/离线估计，若低估了耦合强度，引理给出的界会乐观；这是「契约充分性」问题的数学化身。

### 定理 14（分层组合可靠性）

**陈述**：若 (i) 所有叶子契约在其假设内对七门可靠；(ii) 每个内部节点满足假设覆盖 A_p ⊆ ⋃_c A_c、兄弟资源非干涉 NI(p)=1、且 sig 一致；(iii) 抬升按 G_p=min(min_c G_c, m_p^couple) 构造；则根计划在 A_root 内执行时，所有叶轨迹通过七门且根边际 ≥ G_root。**证明**：对 DAG 按拓扑序结构归纳。叶子由 (i)。内部节点：由 (ii) 假设覆盖与 NI，子节点实际可达状态落在各自假设内，归纳假设给出各子边际 ≥ G_c；由 (iii) 取 min 得父边际；对全部节点归纳至根。∎

### 定理 15（抬升不增信 / 分层单调）

**陈述**：(i) 对任意内部节点，G_p ≤ min_c G_c（抬升不放大边际）；(ii) 计划层执行集 PlanExec_v6 ⊆ 叶子执行集之投影 ∩ NI；(iii) 当 Δ=0、m_couple=+∞、NI 恒真时，分层认证精确退化为逐叶七门认证，即 PlanExec_v6 = Exec_v5（在叶子层）。**证明**：(i) 由 min 的定义。(ii) 父层执行要求所有子层执行且 NI 成立，故是子层执行集的交与投影的子集。(iii) 退化条件下 lift 只做并/交而不加约束。∎

**工程含义**：抽象层不是「安全放大器」；父层永远不能比最弱子层更安全。这直接否定了「用高层证书掩盖低层风险」的做法。

### 定理 16（可复现裁决）

**陈述**：设认证在给定 CBOM 下确定性（数值误差 ≤ ε_num），且验证器与门谓词属于 TCB。若两方对同一 (B_cert, x) 得到不满足 ≡_ε 的证书，则必存在可检测的差异：CBOM 哈希不同，或硬件/工具链指纹不同，或验证器不在 TCB。因此第三方可用同一 B_cert 重放并裁决。**证明**：确定性 ⇒ 相同 B_cert 与相同 TCB 必得 ≡_ε 结果；逆否即得。CBOM 哈希承诺了全部安全相关构件，故差异必落在承诺项上。∎

**诚实边界**：浮点/GPU 非确定性、闭源驱动、时钟/并发会让「逐位可复现」退化为「ε 内可复现」；ε_num 的选取本身是工程妥协。

### 定理 17（供应链与分叉单调性）

**陈述**：设贡献序列 c_1,…,c_n 均满足 Acc（特别是差分认证 ΔExec(c_k)⊆∅），且门/阈值改动必产生新 CBOM。则 (i) Exec 沿序列单调不增：Exec_{k+1} ⊆ Exec_k；(ii) 任何削弱门的开源分叉产生 fork_id' ≠ fork_id，其证书不能被上游验证器接受（fail-closed）；(iii) 因此开放贡献无法静默扩大执行集。**证明**：(i) 对 k 归纳，由 ΔExec⊆∅。(ii) 由 CBOM 哈希承诺门代码与阈值，改动必改变哈希；`accept_cross_fork` 要求哈希相等。(iii) 综合 (i)(ii)。∎

**诚实边界**：差分认证在连续轨迹空间上只能「可证界 + 经验采样」；若验证器本身被攻陷（TCB 根失守），定理失效——这是所有供应链安全的共同前提。

### 定理 18（TCB 最小化保持证书不变性）

**陈述**：将提议器 π_FM、记忆 LMEM-v2、FER FAMK 移出 TCB 不改变执行边界：Exec_v6 只依赖 {kc_i, τ^5, 验证器}，与这些不可信构件无关；它们只影响提议分布支撑、完备性与时延。**证明**：由 v5 定理 6（证书不变性），执行集 {x: ∧_i kc_i(x;τ^5)=1} 与提议分布无关；kc_i 与 τ^5 均在 TCB 内，其余构件不出现在谓词中。∎

### 定理 v6（开放分层认证栈总装）

**陈述**：在 v5 假设 (B1)~(B7) 及新增 (B9) 契约覆盖与耦合界、 (B10) 认证在 CBOM 下 ε-确定性 下：
(i) 分层组合可靠（定理 14）；
(ii) 抬升不增信，PlanExec_v6 ⊆ 叶子执行投影（定理 15）；
(iii) 可复现裁决（定理 16）；
(iv) 供应链/分叉单调，开放贡献不能扩大 Exec（定理 17）；
(v) TCB 最小化保持证书不变性（定理 18）；
(vi) 原子 Exec_v6 ⊆ Exec_v5（门与 τ^5 冻结 + CBOM/TCB 附加谓词只删不增），退化条件下精确相等。

**证明**：由定理 14~18 与 v5 定理 6 组合。∎

**诚实声明**：(i) 契约充分性（B9）无法被系统自证，只能人工/红队/形式化工具部分验证；(ii) ε-确定性（B10）在异构硬件/闭源驱动上难保证；(iii) 差分认证对连续空间只能给可靠内近似 + 采样证据，非完全证明；(iv) TCB 根（签名/维护者）被攻陷时全部保证失效；(v) 分层契约的版本/依赖管理会累积维护负债。

## 7. 本轮最大风险（最终确认）

**一句话**：**契约充分性不可证**——分层组合的可靠性完全依赖人手写的 assume-guarantee 契约；若父层假设漏掉一个耦合项（共享物体、力预算、时序），每个子节点仍能通过各自的门，证书也完全可复现，而父层计划实质不安全。开源与可复现只能验证「计算与来源」，不能验证「契约是否充分」；社区评审降低但无法证明充分性，系统可能稳定地、可复现地铸出一张错误的证书。
