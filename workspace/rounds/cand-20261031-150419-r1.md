# 第 1 轮（新灵感循环）· EDGE-JP：云端 VLA 规划 + 边缘关节空间放置相位 + 演示学到的释放门控

> 承接第 10–12 轮（FACT-VLA → GEO-RESIDUAL → CHUNK-SERVO）。本轮不推倒重来，而是把 CHUNK-SERVO 的“最后 3 厘米视觉闭环”继续往下推到 **执行相位**：关节空间、放置释放、边缘 30Hz。
>
> 三个灵感词：**关节空间控制 / 放置 / 边缘计算**。

## 0. 先给结论：缺的不是“更会想”，而是“最后 3 厘米的执行相位”

第 12 轮 CHUNK-SERVO 的判断仍然成立：榜首不到 30%，瓶颈在最后 3 厘米的闭环。但本轮补上一个更具体的诊断：

- **空间缺口**：官方 WLA 输出 EE 动作，挑战赛也允许 EE 控制；EE 6D 只约束末端，7-DoF 手臂的 1 维冗余没有被控制。插入类任务里，肘部姿态会显著影响能否进入狭小空间；本轮数据里 PlugInEthernet 的肘部残差中位数 0.077 rad，是 HangCup 的 4.4 倍。
- **相位缺口**：placement 不是“到达即成功”，而是 **减速 → 对准 → 释放 → 撤退** 的相位转换。本轮在 HangCup 686 次、PlugInEthernet 422 次释放事件上看到一致的“释放前减速、释放后加速”：HangCup 末端速度从 0.065 m/s 降到 0.043 m/s，释放后升到 0.357 m/s；PlugInEthernet 从 0.165 m/s 降到 0.094 m/s，释放后升到 0.196 m/s。一个不建模相位的 chunk 策略，很容易在“还在动”的时候松手。
- **算力/延迟缺口**：6B VLA + 远程 API + 30Hz 控制，不可能靠云端闭环。离线数据还测到 **67–100 ms 的命令-状态延迟**（`action[t]` 与 `state[t+2..3]` 最匹配）。边缘执行器必须显式补偿这个延迟，而不是把它当成噪声。

所以本轮主押注是 **EDGE-JP**：

> **云端只做低频语义规划（EE 或关节目标），边缘每个端口跑 30Hz 的关节空间执行器；执行器用演示学到的“减速-对准-释放-撤退”门控决定何时松手，用实测 67–100 ms 延迟做相位对齐，用 7-DoF 零空间先验解决插入姿态。**
>
> 它不是第二个学习模型：VLA 仍是唯一策略模型，IK / 重定时 / 释放门控 / 安全滤波都是确定性控制器；演示先验是查表统计，不是策略网络。

## 1. 本轮新核实的事实（只列会改变方案的）

### 1.1 规则与 API：单模型、全局 action space、无深度/力/触觉（A）

- 32 任务、同一模型、每任务 10 次、5 类泛化各 2 次、单次 ≤180 s；排名 = 平均成功率 → 平均步骤分 → 更早提交；N 台机器人、端口 8765 起连续 N 个、每端口独立 `reset()`；另有**不计分单任务测试通道**。
- `control_space` 只能全局选 `"joint"` 或 `"ee"`，互斥；joint 动作 = 双臂 7+7、grippers 1+1、`pivot` 7；ee 动作 = 双臂绝对 EE 位姿 6+6、grippers、`pivot` 7。
- 观测只有四路 RGB 480×640：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`；**没有 depth / camera_info / force / tactile**。
- 推论：EDGE-JP 必须是每端口独立、CPU 轻量、确定性、不能抢 VLA GPU 的执行层；不能依赖点云或力控；joint vs ee 的 A/B 只能在单任务通道做，正式提交只能选一个。

### 1.2 数据：33k 演示、30Hz、关节动作可用；动作有 2–3 帧超前（A + 本轮 B）

- 32 个 HF 数据集合计 **33,276 episodes / 18,282,246 frames / 169.28 h / 30 fps**；HangCup 平均 6.2 s，ToolboxStorage 平均 37.6 s。
- 头双目已标定：基线 **58.2526 mm**、`fx≈282.37`、`rectified=true`；腕部相机没有内参；`state_d435` 是头相机在 base 系的位姿；`lower_body[-3:]=waist`。
- 本轮下载 `G1_Dex1_HangCup` 和 `G1_Dex1_PlugInEthernet` 的 `file-000.parquet` 做离线分析：HangCup **719 eps / 130,565 frames**；PlugInEthernet **211 eps / 129,272 frames**。
- **动作超前**：把 `action[t]` 与 `state[t+k]` 对齐，HangCup 左/右臂最佳 `k=3/2`，PlugInEthernet 双臂最佳 `k=3`；平均绝对误差相对 `k=0` 下降约 **40–55%**。EE 动作同样最佳 `k=2–3`。结论：数据里的动作是“未来 67–100 ms 的目标”，不是当前状态。
- **冗余使用是任务相关的**：用 EE 位姿线性回归肘关节，HangCup 残差中位数 **0.0174 rad**（p90 0.0520），PlugInEthernet **0.0768 rad**（p90 0.1253）。悬挂任务的肘部基本由 EE 决定；插入任务会主动用肘部冗余。
- **释放是相位转换**：HangCup 检测到 686 次释放、PlugInEthernet 422 次；释放前 8 帧平均 EE 速度分别降到 0.043 / 0.094 m/s，释放后 12 帧升到 0.357 / 0.196 m/s。释放不是“到达点”的瞬时事件，而是一个先减速再离开的过程。
- **负结果（本轮要剪掉的）**：原始关节跟踪残差 `||state[t+3]-action[t]||` 与 EE 速度的相关系数中位数是 HangCup **0.903**、PlugInEthernet **0.844**。它主要反映运动滞后，不是干净的接触信号。第 11 轮设想的“用跟踪误差做无传感器接触检测”不能直接搬；要么做速度补偿后的残差模型，要么本轮先放弃 CFT。

### 1.3 官方 WLA：6B、EE 动作、没有手臂关节槽（A）

- UnifoLM-WLA-1.0 是 6B 模型；54 维动作空间包括 EE / gripper / hand / waist / torso / base / legs，**没有 14 个手臂关节槽**；默认 `chunk_size=30`、`target_fps=30`；输出相对 EE；冻结 VLM、只训 DiT action head + robot-state projector，约 24GB GPU 可微调。
- 推论：**纯关节空间 VLA 必须换/新训 action head**，这不是本轮的低风险路径。低风险路径是：WLA 继续输出 EE 规划，边缘用冗余 IK 转成关节目标，再执行 EDGE-JP 的放置相位。高成本路径才是把 WLA action head 改成关节输出（仍是一个模型），作为 J1 实验。

### 1.4 榜单：29.7% 仍是“预览上限”，不是实时 SOTA（A + B）

- 官网 leaderboard / runs 当前显示 **“Coming Soon”**；`leaderboard_data.json` 仍有 8 个模型：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。
- 但 JSON 的 `generated_from=gen_leaderboard.py`，先前分析显示步骤-成功率近似线性、R²>0.999999，且成功率不是 10 次试验的整数倍；这不是真实 320 trials 的结果。
- 结论不变：把 29.7% 当难度信号/预览上限可以；不要把它当 SOTA、任务难度表或失败分布。本轮不从榜单排名挖创新点。

### 1.5 文献：混合动作空间 + 放置 + 边缘，三条线刚好拼上（A）

- **动作空间**：`Demystifying Action Space Design for Robotic Manipulation Policies`（arXiv:2602.23408，2026-10-31 检索）在 13,000+ 真机 rollouts / 500+ 模型上发现：**delta 动作一致更好；joint-space 更利于控制稳定性，task-space 更利于泛化**。这直接支持“task-space VLA 规划 + joint-space 边缘执行”的混合，而不是二选一。
- **冗余**：`Redundancy-aware Action Spaces for Robot Learning`（ERJ，arXiv:2406.04144 / DOI 10.1109/LRA.2024.3416074）指出 joint-space 精确但训练效率低、task-space 数据效率高但狭小空间受限，ERJ 用末端冗余把两者结合；ERJ 在需要精确本体构型的任务上更好。对应到本轮：插入任务需要控制肘部，不能只给 EE。
- **关节速度**：`Benchmarking Action Spaces in RL for Vision-based Robotic Manipulation`（arXiv:2606.18594）在 picking/pushing 的 sim-to-real 中发现 joint velocity 最平滑、最终性能最好。说明关节空间执行不是倒退，至少值得 A/B。
- **放置**：`AnyPlace`（arXiv:2502.04531）用 VLM 粗定位 + 局部点云预测放置位姿，在 insertion/stacking/hanging 上很强；但它依赖局部点云/深度，而挑战赛 API 没有 depth。**不能直接移植**；本轮改用 RGB + 本体感觉 + 演示释放时序，走轻量确定性路线，与 AnyPlace 是互补而非重复。
- **边缘执行时钟**：`Shared Execution-Clock Drifting (SECD)`（arXiv:2609.23305）把执行节奏显式建模成共享单调时钟，在 NVIDIA Thor 上做动态精度操作，300 trials 平均 77.0%。这支持 EDGE-JP 的“边缘重定时 + 释放时钟”，而不是把 chunk 当固定时间表。
- **边缘模型**：SmolVLA 450M（arXiv:2506.01844；HF blog）可在消费级 GPU 甚至 CPU 上跑，异步推理快 30%、吞吐 2×。它是 J2 的可选底座：如果 WLA 6B 太重，可以用 450M 关节/EE 模型做边缘侧的低成本 VLA。

## 2. 诊断：三个缺口，正好对应三个词

### 2.1 空间缺口：EE-only 控制丢掉了 7-DoF 冗余

- 挑战赛 joint 接口给的是 7+7 手臂关节；EE 接口只有 6+6 位姿。EE 控制下，IK 的零空间分支是“任选”的；同一个末端位姿，肘部可以在不同位置。
- 数据说明这不是理论问题：PlugInEthernet 的肘部残差 0.077 rad（p90 0.125），HangCup 只有 0.017 rad。插入任务确实在用冗余；如果边缘 IK 不控制零空间，就可能选到撞桌沿/限位的分支。
- 关节空间还能做逐关节限位、速度限制、自碰撞和桌面安全滤波；EE 空间做这些要绕一圈。**关节空间是放置相位的自然控制空间。**

### 2.2 相位缺口：placement 是“减速-对准-释放-撤退”，不是“到达即可”

- 释放前减速、释放后加速，在 HangCup 和 PlugInEthernet 上都成立。一个 chunk 策略如果只优化“到目标点的距离”，会在速度还很高时松手；松手后物体带着动量飞出/倒下，成功率就掉了。
- 释放门控不需要新模型：它只需要 **速度、关节稳定性、目标/对准误差、持续时间** 四个量。这些量在 30Hz 的边缘循环里都能拿到，且是确定性的。
- 释放后还需要一个短撤退（沿插入轴/远离支撑面），避免夹爪/手指把刚放好的物体碰倒。这个也可以在边缘状态机里做。

### 2.3 算力/延迟缺口：云端 VLA 不可能 30Hz 闭环

- 6B VLA 的一次前向 + 网络 RTT + 评测端排队，通常远大于 33ms；chunk=30 时一次决策要覆盖 1 s。云端只能做低频规划。
- 离线数据测到 67–100 ms 的命令-状态延迟；这意味着“当前状态”和“刚发出的命令”不是同一时刻。边缘执行器如果直接拿当前状态减当前命令算误差，会高估误差、误判接触/稳定。
- 边缘执行器可以：缓存最新 chunk、30Hz 重定时、按延迟对齐反馈、在 chunk 迟到时保持/衰减、在释放相位降速。这些都是 CPU 级操作，不抢 GPU。

## 3. 方法：EDGE-JP

### 3.1 总架构

```
┌──────────────────────────────┐
│ 云端：唯一学习模型 VLA        │
│  - WLA-1.0 6B（EE 规划）      │
│  - 或 SmolVLA 450M（EE/关节） │
│  输出：H 步目标 chunk          │
└──────────────┬───────────────┘
               │ 低频率（1–5 Hz）
┌──────────────▼───────────────┐
│ 边缘：每端口一个 worker       │
│  1. Adapter（帧/动作语义）    │
│  2. 冗余 IK + 姿态先验（TRP） │
│  3. 关节重定时（ERT）         │
│  4. 释放门控（RG）            │
│  5. 安全滤波（SF）            │
│  30 Hz 输出 joint actions     │
└──────────────┬───────────────┘
               │ API
┌──────────────▼───────────────┐
│ 评测端：N 台机器人 / N 端口   │
└──────────────────────────────┘
```

- **唯一学习模型**：VLA。边缘全部是确定性控制器。
- **每端口独立**：一个端口一个 worker、一个状态机、一个 chunk 缓冲；N 个端口可并行，互不共享可变状态。
- **双频**：VLA 低频规划，边缘 30Hz 执行；这正是第 12 轮 CHUNK-SERVO 的双频思想，但执行层从 EE 伺服升级为关节空间放置相位。

### 3.2 LJC：Lead-aware Joint Chunking（延迟对齐的关节 chunk）

- 离线标定 `δ`：对每个任务/每只手臂，找使 `||action[t] - state[t+k]||` 最小的 `k`；本轮 HangCup/PlugInEthernet 都是 `δ=2–3` 帧（67–100 ms）。
- 反馈对齐：计算跟踪误差/稳定度时，用 `state[t]` 对齐 `action[t-δ]`，而不是 `action[t]`；否则会把执行滞后误判成接触或超调。
- IK 对齐：如果从 EE 规划转关节，求解的是 `x_target[t+δ]` 对应的关节，而不是当前 `x_state[t]`；这样关节目标与低层控制器的实际跟踪相位一致。
- 如果训练关节 action head（J1）：直接学 `action[t]` 的绝对关节目标，或学 `q_target[t+δ] - q_state[t]` 的 delta；两种都保留 `δ`，不要额外再加前馈超前。

### 3.3 RG：Release Governor（释放门控）

状态机：

```
APPROACH → ALIGN → SLOW → RELEASE → RETREAT
```

释放条件（全部满足并持续 N 帧）：

1. `||v_ee|| < v_thr`：末端速度低于任务阈值；
2. `||qdot|| < qdot_thr`：关节速度稳定；
3. `||x_ee - x_target|| < e_thr` 或腕部图像对准误差低于阈值；
4. 持续 `N=3–5` 帧（100–167 ms），避免瞬时抖动静止误触发。

阈值来源：

- **本体感觉版 RG-P（优先）**：`v_thr` 取演示释放前速度的 0.5–0.8 倍；HangCup 释放前 8 帧 0.043 m/s，PlugInEthernet 0.094 m/s；先按任务族给初值，再用单任务通道校准。
- **视觉版 RG-V（可选）**：用腕部图像对演示释放关键帧做模板/关键点匹配；只做确定性匹配，不引入第二个学习模型。若腕部无内参、标定不稳，先不用。
- **相对阈值**：`v_thr = 0.7 × median(approach 段速度)`，比固定绝对值更容易跨任务迁移。

释放后：

- 保持夹爪张开 3–5 帧；
- 沿插入轴/远离支撑面方向做短撤退（例如 1–2 cm，速度限制）；
- 回到 APPROACH 或任务终止条件。

### 3.4 TRP：Task-conditioned Redundancy Prior（任务相关冗余先验）

- 对每个任务/物体族，从演示里提取释放时刻的肘关节/零空间姿态分布，作为先验 `q_prior`。
- IK 用阻尼最小二乘 + 零空间投影：

\[
\Delta q = J^\top (JJ^\top + \lambda^2 I)^{-1} e
+ (I - J^\top (JJ^\top)^{-1} J)\,\nabla h(q)
\]

其中 `h(q)` 是到演示姿态先验的距离；零空间项只改肘部，不改末端。
- 插入类任务（PlugInEthernet、PlugCharger、ArrangeTestTubes）使用较强先验；悬挂/堆叠类（HangCup、StackBowls）使用较弱先验，因为数据表明肘部主要由 EE 决定。
- 先验不是策略网络：它是演示统计的查表/高斯，离线生成，在线只做加权。

### 3.5 ERT：Edge Retimer（边缘重定时）

- 把 VLA chunk 的关节目标按最小 jerk 插值到 30Hz；限制关节速度/加速度；到点后保持。
- 新 chunk 到达时，从当前状态平滑 blend 到新 chunk 的第一个目标，避免跳变。
- chunk 迟到/丢失时，保持最后一个目标并衰减；超过超时则回到安全保持位。
- 用**共享单调执行时钟**（参考 SECD）记录 chunk 的生成时刻、到达时刻、执行时刻；释放门控用同一个时钟，避免“规划时间”和“执行时间”漂移。

### 3.6 SF：Safety Filter（安全滤波）

- 关节限位、速度限位、加速度限位；
- 自碰撞粗检（用 URDF 的胶囊/包围球近似）；
- 桌面/支撑面平面约束；
- IK 失败/超时 → 保持上一有效目标；连续失败 → 请求 VLA 重规划。
- 安全滤波是最后一道，不改变 VLA 的语义规划。

### 3.7 单模型合规

- VLA 是唯一学习模型；IK / 重定时 / 释放门控 / 安全滤波都是确定性代码。
- 演示先验是离线统计表，不是学习到的策略；不加载第二个网络。
- 如果做 J1（关节 action head），它是同一个 VLA checkpoint 的一部分，不是新模型。
- 如果规则对“模型”作最宽解释，提交物里只打包一个 VLA + 确定性执行代码；不引入单独的释放分类器。

## 4. 证据：为什么是现在

### 4.1 动作超前：执行层必须按 δ 对齐

| 任务 | 手臂 | k=0 平均绝对误差 | 最佳 k | 最佳误差 | 降幅 |
|---|---|---:|---:|---:|---:|
| HangCup | 左 | 0.01909 rad | 3 | 0.01138 rad | 40.4% |
| HangCup | 右 | 0.02742 rad | 2 | 0.01352 rad | 50.7% |
| PlugInEthernet | 左 | 0.02748 rad | 3 | 0.01223 rad | 55.5% |
| PlugInEthernet | 右 | 0.03056 rad | 3 | 0.01497 rad | 51.0% |

这不是“多加一个前馈”的理由，而是“反馈必须对齐”的理由。EDGE-JP 的 LJC 就是把 δ 显式化。

### 4.2 冗余：插入任务真的在用肘部

| 任务 | 肘部残差中位数 | p90 | \|corr(肘, EE.x)\| | 关节 >5Hz 能量比 | EE >5Hz 能量比 |
|---|---:|---:|---:|---:|---:|
| HangCup | 0.0174 rad | 0.0520 rad | 0.592 | 0.0013 | 0.0020 |
| PlugInEthernet | 0.0768 rad | 0.1253 rad | 0.685 | 0.0013 | 0.0009 |

注意：**关节并不总是比 EE 更平滑**（HangCup 关节略好，PlugInEthernet EE 略好）。所以本轮不以“平滑”作为卖点；卖点是**冗余可控 + 限位/安全 + 插入姿态**。

### 4.3 释放：一致的“先慢后快”

| 任务 | 事件数 | t-20 EE 速度 | t-8 EE 速度 | t0 EE 速度 | t+12 EE 速度 | t-8 夹爪 | t0 夹爪 |
|---|---:|---:|---:|---:|---:|---:|---:|
| HangCup | 686 | 0.0653 m/s | 0.0430 m/s | 0.1320 m/s | 0.3567 m/s | 0.178 | 2.537 |
| PlugInEthernet | 422 | 0.1646 m/s | 0.0940 m/s | 0.1344 m/s | 0.1956 m/s | 0.856 | 2.579 |

释放门控的物理依据就在这里：**松手前速度已经降到低谷，松手后手臂才加速离开**。如果策略在 t-20 的速度下松手，物体动量会大 1.5–2 倍。

### 4.4 负结果：不要直接用原始跟踪残差做接触检测

- `corr(||state[t+3]-action[t]||, ||v_ee||)`：HangCup 中位数 **0.903**（p10 0.828，p90 0.949）；PlugInEthernet **0.844**（p10 0.787，p90 0.889）。
- 这说明原始跟踪残差主要是运动滞后，不是接触力/碰撞。第 11 轮的 CFT 设想在本轮被剪掉；如果以后要做，必须先用速度/加速度模型补偿，再看残差尖峰，且需要真机验证。

## 5. 与第 12 轮 CHUNK-SERVO 的关系

**保留**：

- 双频思想：VLA 低频规划，执行器高频闭环；
- 演示检索/相对目标：33k 成功演示是资产；
- 数字孪生标定：RTT、延迟、增益；
- 单任务不计分通道：唯一敢做 A/B 的地方；
- 任务分档：A 档伺服优先、B 档 VLA 优先、C 档低投入。

**升级**：

- 执行层从 EE 视觉伺服升级为 **关节空间 + 放置相位**；
- 增加释放门控 RG、重定时 ERT、冗余先验 TRP、安全滤波 SF；
- 把“最后 3 厘米”从“视觉对准”扩展为“对准 + 减速 + 释放 + 撤退”。

**剪枝**：

- 原始 CFT（跟踪误差当接触检测）：被 0.84–0.90 的速度相关性证伪；
- 从零训 6B 关节 VLA：官方 WLA 是 EE，成本/风险不匹配；
- 依赖深度的 AnyPlace 式放置位姿预测：API 没有 depth；
- 30Hz 广域视觉伺服：远程 API + 无深度，不可行；
- 第二个学习模型/逐任务策略：单模型合规风险；
- 把 29.7% 当 SOTA 去追：榜单是预览数据。

## 6. 竞赛策略：先 A/B，再烧正式 trials

- `control_space` 是全局的，不能按任务切换；正式提交只能选 joint 或 ee。
- **释放门控与动作空间解耦**：RG 可以叠加在 EE 策略上，也可以叠加在 joint 策略上。即使 joint 输了 A/B，RG 仍然可能贡献 placement 成功率。这是本轮的下限保护。
- **单任务 A/B（不计分）**：T01 HangCup、T27 StackBowls、T26 PlugInEthernet、T19 ZipUp、T16 FoldTowel；每任务 10 次，比较：
  - EE baseline（CHUNK-SERVO）；
  - EE + RG；
  - joint + RG；
  - joint + RG + TRP。
- **指标**：成功率、释放时刻误差（相对演示/人工标注）、time-to-place、失败模式（早释放/晚释放/撞倒/未对准/超时）。
- **预算**：先用 5×10=50 次不计分 trials，确认 RG 的收益和 joint 的收益；再决定 1–2 次正式提交。不要用 320 次正式 trials 做未验证的 A/B。
- **任务组合**：优先 placement/insertion 瓶颈任务；HangCup、StackBowls、PlugInEthernet、ZipUp、FoldTowel 覆盖悬挂、堆叠、插入、拉链、折叠五种接触模式。

## 7. 实验门 G0–G5

- **G0 语义/接口**：确认 joint 动作是绝对目标/增量、`pivot` 7 维语义、EE 帧与 WLA 帧的 TCP 偏移；用 `example_env.py` 和一条演示做回放。未过 G0 不做任何训练。
- **G1 释放门控离线**：在留出 episodes 上跑 RG-P，测释放事件的 precision/recall、释放时刻误差、误触发率；目标 recall ≥90%、时刻误差 ≤3 帧、误触发 <5%。
- **G2 冗余 IK**：在 PlugInEthernet 演示上比较“无先验 IK”和“TRP IK”的 IK 成功率、限位余量、肘部先验误差；目标 IK 成功率 ≥99%、限位违规下降 ≥20%。
- **G3 仿真延迟**：在数字孪生里注入 0/50/100/150 ms RTT，比较 EE baseline / EE+RG / joint+RG 的成功率与收敛时间；目标是在高延迟下 EDGE-JP 不崩。
- **G4 真机单任务 A/B**：5 任务 ×10 次；目标是 placement 任务绝对成功率 +10%，其他任务不回退 >5%。
- **G5 正式提交**：只有 G4 通过才烧 320 trials；根据 A/B 选全局 joint 或 ee；RG 默认开启。

## 8. 风险

- **单模型合规**：VLA 是唯一学习模型；IK/RG/ERT/SF 必须保持确定性；不加载第二个网络。若规则解释更严，提交物只打包一个 checkpoint + 执行代码。
- **IK/标定**：腕部无内参、EE 帧可能差 TCP 偏移；先做手眼/工具坐标校准，再做 RG-V；RG-P 不依赖腕部内参，优先。
- **阈值迁移**：演示阈值可能过拟合 HangCup/PlugInEthernet；用相对阈值 + 单任务通道校准；未见物体上先用保守阈值。
- **延迟变化**：离线 δ 可能随部署/网络变化；在线估计 δ（用动作-状态互相关）或每端口启动时标定。
- **动作语义**：joint 动作是绝对还是增量、`pivot` 7 维定义未逐维确认；G0 必须先过。
- **数据泄漏**：释放门控在训练任务上校准、在同任务留出 episodes 上验证；不要用测试任务调阈值。
- **排名方差**：每任务 10 次，成功率的标准误很大；A/B 要看配对任务/多种子，不要用单任务一次结果下结论。

## 2. 数据分析（B）

### 2.1 方法

- 数据：`G1_Dex1_HangCup` 与 `G1_Dex1_PlugInEthernet` 的 `file-000.parquet`；按 `episode_index` 切分 episode；30Hz。
- HangCup：719 episodes / 130,565 frames；PlugInEthernet：211 episodes / 129,272 frames。
- 动作超前：对 `k=0..6`，计算 `mean(|action[t] - state[t+k]|)`，按左/右臂 7 关节取平均；EE 位姿同样比较。
- 冗余：每个 episode 内，用 EE 位姿（xyz+rpy）线性回归肘关节（joint index 3），取残差标准差；同时算 `|corr(elbow, EE.x)|`。
- 平滑度：每路信号按自身标准差归一化，计算 >5Hz 能量占比；对关节/EE 取 episode 中位数。
- 释放：每 episode 每只手臂，找夹爪状态从低到高跨过 50% 量程的最后一个持续上升沿；以该帧为中心取 ±20 帧，平均 EE 速度、关节跟踪残差、夹爪值。
- 跟踪残差：`||state[t+3] - action[t]||`（按 δ=3 对齐）；与 EE 速度做 episode 内相关。
- 所有统计都是**离线 replay 的效应量**，不是真机成功率；release 事件是启发式检测，未逐条人工核验。

### 2.2 动作超前：67–100 ms 的命令-状态延迟

| 任务 | 手臂 | k=0 平均绝对误差 | 最佳 k | 最佳误差 | 降幅 |
|---|---|---:|---:|---:|---:|
| HangCup | 左 | 0.01909 rad | 3 | 0.01138 rad | 40.4% |
| HangCup | 右 | 0.02742 rad | 2 | 0.01352 rad | 50.7% |
| PlugInEthernet | 左 | 0.02748 rad | 3 | 0.01223 rad | 55.5% |
| PlugInEthernet | 右 | 0.03056 rad | 3 | 0.01497 rad | 51.0% |

- 逐关节最佳 k 也在 2–3 之间；EE 动作同样最佳 `k=2–3`。
- 解释：数据里的动作是低层控制器要跟踪的目标；当前状态比目标晚 2–3 帧（67–100 ms）。
- 设计含义：反馈误差必须用 `state[t]` 对齐 `action[t-δ]`；IK 目标也要按同一相位解释。不要在这个延迟之外再叠加未经验证的前馈超前。

### 2.3 冗余与平滑度：插入任务在用肘部，关节不一定更平滑

| 任务 | 肘部残差中位数 | p90 | \|corr(肘, EE.x)\| | 关节 >5Hz 能量比 | EE >5Hz 能量比 |
|---|---:|---:|---:|---:|---:|
| HangCup | 0.0174 rad | 0.0520 rad | 0.592 | 0.0013 | 0.0020 |
| PlugInEthernet | 0.0768 rad | 0.1253 rad | 0.685 | 0.0013 | 0.0009 |

- PlugInEthernet 的肘部残差是 HangCup 的 4.4 倍：插入任务确实在使用 7-DoF 冗余。
- 平滑度没有一致优势：HangCup 关节略好，PlugInEthernet EE 略好。**不要把“关节更平滑”作为主论点**；主论点是“冗余可控 + 限位/安全 + 插入姿态”。
- 设计含义：TRP（任务相关冗余先验）主要给插入类任务；悬挂/堆叠类可以弱化。

### 2.4 释放相位：先减速，再松手，再加速离开

| 任务 | 事件数 | t-20 EE 速度 | t-8 EE 速度 | t0 EE 速度 | t+12 EE 速度 | t-8 夹爪 | t0 夹爪 |
|---|---:|---:|---:|---:|---:|---:|---:|
| HangCup | 686 | 0.0653 m/s | 0.0430 m/s | 0.1320 m/s | 0.3567 m/s | 0.178 | 2.537 |

- PlugInEthernet：0.094 → 0.196 m/s；幅度小一些，但“先降后升”的形状一致。
- 设计含义：释放门控应在速度低谷触发；松手后短撤退，避免碰倒刚放好的物体。

### 2.5 负结果：原始关节跟踪残差不是接触检测器

- `corr(||state[t+3]-action[t]||, ||v_ee||)`：HangCup 中位数 **0.903**（p10 0.828，p90 0.949）；PlugInEthernet **0.844**（p10 0.787，p90 0.889）。
- 跟踪残差与运动速度高度相关：它主要反映执行滞后，而不是接触力/碰撞。
- **剪枝**：第 11 轮设想的原始 CFT（用跟踪误差做无传感器接触检测）不能直接用。若以后要做，需要先建立速度/加速度补偿模型，再看残差尖峰；本轮不做。

### 2.6 限制

- 只分析了每个任务的一个 parquet 文件（HangCup 719/1043 eps；PlugInEthernet 211/1009 eps），不是全量。
- 释放事件用夹爪 50% 量程上升沿启发式检测；未逐条人工核验；PlugInEthernet 有多次抓放，取的是最后一次释放。
- 没有真机、没有闭环执行、没有跨任务泛化；所有数字是离线 replay 的效应量。
- 这些限制不影响“动作有延迟、插入用冗余、释放前减速”三个定性结论，但影响阈值的具体数值。

## 3. 问题形式化

### 3.1 记号

- \(q_t \in \mathbb{R}^{14}\)：双臂关节（每臂 7）。
- \(x_t \in SE(3)^2\)：双臂 EE 位姿。
- \(a_t\)：策略输出的动作（绝对关节目标或增量）。
- \(f: \mathbb{R}^7 \to SE(3)\)：单臂正运动学；\(J = \partial f / \partial q\)。
- \(\delta\)：命令-状态延迟（帧），本轮实测 2–3。
- \(H\)：VLA chunk 长度；\(T_s=1/30\) s。

### 3.2 延迟对齐

数据支持：

\[
a_t \approx q_{t+\delta}, \qquad \delta \in \{2,3\}.
\]

因此反馈误差用

\[
e_t = \| q_t - a_{t-\delta} \|
\]

而不是 \(\|q_t-a_t\|\)。如果控制器把 \(a_t\) 当作“当前目标”，会把正常的执行滞后误判成超调或接触。

### 3.3 冗余 IK + 姿态先验

给定目标 \(x^\star_{t+\delta}\) 和先验 \(q^{prior}\)：

\[
q^\star = \arg\min_q \| f(q) - x^\star_{t+\delta} \|_W^2 + \lambda \| q - q^{prior} \|^2
\]

subject to \(q_{min} \le q \le q_{max}\)，\(|\dot q| \le \dot q_{max}\)，自碰撞/桌面约束。

阻尼最小二乘 + 零空间投影：

\[
\Delta q = J^\top (JJ^\top + \lambda^2 I)^{-1} e
+ (I - J^\top (JJ^\top)^{-1} J)\,\nabla h(q),
\]

其中 \(h(q)=\|q-q^{prior}\|^2\)。零空间项只改肘部/冗余，不改末端一阶误差。

先验来源：

- 对每个任务族，从演示的释放时刻提取肘关节分布；
- 插入类（PlugInEthernet、PlugCharger、ArrangeTestTubes）用较强先验；
- 悬挂/堆叠类（HangCup、StackBowls）用较弱先验，因为肘部主要由 EE 决定。

### 3.4 释放门控

离散门控：

\[
g_t = \mathbf{1}\left[
\|v_t\| < v_{thr}
\;\land\;
\|\dot q_t\| < \dot q_{thr}
\;\land\;
\|e_t\| < e_{thr}
\right].
\]

要求 \(g_{t-N+1:t}=1\) 才触发释放，\(N=3–5\) 帧（100–167 ms）。

- \(v_t\)：EE 线速度；\(\dot q_t\)：关节速度；\(e_t\)：目标/对准误差。
- \(v_{thr}\)：初值取演示释放前速度的 0.5–0.8 倍；HangCup 约 0.02–0.04 m/s，PlugInEthernet 约 0.05–0.08 m/s；再用单任务通道校准。
- 相对阈值：\(v_{thr}=0.7\times \mathrm{median}(v_{\text{approach}})\)，比固定值更易跨任务迁移。
- \(e_{thr}\)：有腕部模板时用图像对准误差；没有时用 EE 目标误差 + 关节稳定度。
- 释放后保持张开 3–5 帧，再沿插入轴/远离支撑面短撤退 1–2 cm。

### 3.5 边缘重定时

给定关节 waypoint \(q_0, q_1\) 和时间 \(T\)，用最小 jerk：

\[
s(\tau)=10\tau^3-15\tau^4+6\tau^5,\quad \tau=t/T,
\]

\[
q(t)=q_0+(q_1-q_0)s(\tau).
\]

- 对每段限制 \(\dot q_{max}, \ddot q_{max}\)，必要时拉长时间。
- 新 chunk 到达：从当前 \(q_t\) 到新 chunk 第一个目标做短 blend（3–5 帧）。
- chunk 迟到/丢失：保持最后目标并衰减；超过超时回安全保持位。
- 共享单调执行时钟：记录 chunk 生成/到达/执行时刻；释放门控用同一时钟。

### 3.6 安全滤波

- 关节限位、速度限位、加速度限位；
- 自碰撞粗检（URDF 胶囊/包围球）；
- 桌面/支撑面平面约束；
- IK 失败/超时：保持上一有效目标；连续失败：请求 VLA 重规划；
- 安全滤波是最后一道，不改变 VLA 语义。

## 4. 系统设计

### 4.1 拓扑

```
cloud:
  VLA worker (GPU) ──> chunk queue per port
edge:
  port 0 worker: adapter -> IK+TRP -> ERT -> RG -> SF -> API
  port 1 worker: ...
  ...
evaluator:
  N robots / N ports (8765...)
```

- 每个端口一个独立 worker；不共享可变状态。
- VLA 可以 batch 多端口观测；边缘 worker 只读自己的 chunk。
- 边缘 worker 是 CPU 进程；不抢 GPU。

### 4.2 `get_action` 伪代码

```python
# 每个端口一个实例；evaluator 每次调用 get_action(obs)
def get_action(obs):
    now = clock.now()
    state = parse_obs(obs)                 # q, gripper, images, language
    task = state.language

    # 1) 异步规划：不阻塞 30Hz
    if planner.needs_new_chunk(now):
        planner.request_async(obs, task)   # 后台线程/进程

    # 2) 取当前执行时钟对应的目标
    x_target = chunk_buffer.target_at(now + delta)
    if x_target is None:
        x_target = last_valid_target     # 保持/衰减

    # 3) 冗余 IK + 姿态先验
    q_star = ik_with_prior(
        x_target, q_seed=state.q, q_prior=prior[task],
        limits=limits, collision=collision_model
    )

    # 4) 重定时 + 安全滤波
    q_cmd = retimer.step(q_star, now)
    q_cmd = safety_filter(q_cmd, state.q, limits)

    # 5) 释放门控
    gripper = governor.update(state, q_cmd, x_target, now)

    # 6) pivot 未验证：保持零/上一帧
    pivot = hold_pivot(state.pivot)

    return joint_action(q_cmd, gripper, pivot)
```

### 4.3 边缘步进伪代码

```python
def edge_step(obs):
    q = obs.arm_joints
    x = fk(q)

    # 目标：按延迟 delta 对齐
    x_target = chunk_buffer.target_at(clock.now() + delta)

    # IK：带零空间先验
    q_star = dls_ik(x_target, q, q_prior, limits)

    # 重定时：最小 jerk + 限速
    q_cmd = min_jerk_step(q, q_star, dt=1/30, vmax=..., amax=...)

    # 安全
    q_cmd = clamp_and_avoid(q_cmd, q, limits, table_plane)

    # 释放相位机
    if fsm.state in ("APPROACH", "ALIGN", "SLOW"):
        if release_gate(q, q_cmd, x, x_target, clock.now()):
            fsm.to("RELEASE", t=clock.now())
    if fsm.state == "RELEASE":
        gripper = OPEN
        if clock.now() - fsm.t > 5:
            fsm.to("RETREAT", t=clock.now())
    if fsm.state == "RETREAT":
        q_cmd = retreat_along_insert_axis(q_cmd, step=0.01)
        if fsm.done(clock.now()):
            fsm.to("DONE")

    return q_cmd, gripper, hold_pivot()
```

### 4.4 状态机

```
APPROACH -> ALIGN -> SLOW -> RELEASE -> RETREAT -> DONE
     ^         |        |        |
     |         v        v        v
     +------ RECOVER（超时/IK失败/目标丢失）
```

- APPROACH：向目标接近；速度上限较高。
- ALIGN：末端/腕部对准；速度降低。
- SLOW：进入释放窗口；速度门控生效。
- RELEASE：张开夹爪；保持 3–5 帧。
- RETREAT：沿插入轴/远离支撑面短撤退。
- RECOVER：IK 失败、目标丢失、超时；保持安全位并请求重规划。

### 4.5 Adapter 细节（G0 必须验证）

- **帧**：挑战赛 `*_ee_pose_gripper_base` 是 base 系 xyz+rpy；WLA 的 `*_ee_6d` 是 xyz+rot6d（9 维）。obs adapter 必须 rpy→rot6d；动作 adapter 必须 rot6d→rpy 或直接转四元数。
- **TCP 偏移**：WLA 的 EE 帧与挑战赛的夹爪 TCP 可能差一个夹爪长度；用 `example_env.py` 与一条演示做手眼/工具坐标校准（平移 ≤1 cm、旋转 ≤2°）。
- **pivot**：7 维语义未逐维定义；先保持零/上一帧；验证后再接入。
- **chunk 锚点**：WLA 的相对 EE 动作要先 compose 成 base 系绝对目标，再切片；否则第 6–30 步会以错误锚点解释，产生系统偏移。
- **token**：`meta.token` 必须原样回传。

## 5. 设计依据

### 5.1 文献

- **delta 动作 + 混合空间**：arXiv:2602.23408 在 13,000+ 真机 rollouts / 500+ 模型上发现 delta 动作一致更好；joint-space 更利于控制稳定性，task-space 更利于泛化。EDGE-JP 因此用 task-space VLA 做语义规划、joint-space 边缘执行做稳定控制。
- **ERJ**：arXiv:2406.04144 指出 joint-space 精确但训练效率低、task-space 数据效率高但狭小空间受限；ERJ 用末端冗余结合两者。EDGE-JP 的 TRP 就是“在关节空间里保留末端冗余”的轻量实现。
- **关节速度**：arXiv:2606.18594 在 picking/pushing 的 sim-to-real 中发现 joint velocity 最平滑、最终性能最好。说明关节空间执行值得 A/B。
- **AnyPlace**：arXiv:2502.04531 用 VLM 粗定位 + 局部点云预测放置位姿；强，但依赖深度。挑战赛 API 没有 depth，不能直接移植；EDGE-JP 走 RGB + 本体感觉 + 释放时序的轻量路线。
- **SECD**：arXiv:2609.23305 把执行节奏建模成共享单调时钟，在 NVIDIA Thor 上做动态精度操作，300 trials 平均 77.0%。EDGE-JP 的 ERT/RG 用同一思想：释放时刻属于执行时钟，不属于规划时钟。
- **SmolVLA**：arXiv:2506.01844 / HF blog 的 450M 模型可在消费级 GPU 甚至 CPU 跑，异步推理快 30%、吞吐 2×。它是 J2 的边缘 VLA 选项。

### 5.2 设计原则

1. **任务空间负责“去哪”，关节空间负责“怎么稳”**。
2. **释放是相位，不是点**；用速度/稳定度/持续时间门控，而不是只看距离。
3. **延迟是一等公民**；所有反馈按 δ 对齐，所有 chunk 有生成/到达/执行时钟。
4. **边缘确定性**；不引入第二个学习模型，不把单模型合规赌在规则解释上。
5. **先 A/B 再烧 trials**；control_space 全局，单任务通道是唯一安全的试验场。

### 5.3 什么会证伪 EDGE-JP

- RG 在留出 episodes 上的释放时刻误差 >5 帧，或误触发率 >10%；
- joint + IK 在真机上的跟踪误差显著大于 EE 控制；
- 单任务 A/B 中 placement 任务没有提升，或非 placement 任务回退 >5%；
- `pivot`/joint 动作语义与假设不符，G0 无法通过；
- 释放门控在未见物体/人为干扰下频繁误触发。

任何一条成立，就回退到 CHUNK-SERVO + 仅保留 RG 的下限方案。

## 6. 实验设计

### 6.1 离线（G0–G2）

**G0 语义/接口**：

- 用 `example_env.py` 和一条演示回放，确认 joint 动作是绝对目标还是增量、`pivot` 7 维含义、EE 帧/TCP 偏移。
- 通过标准：动作回放后关节轨迹与演示状态的均方误差 <0.02 rad；pivot 不导致下身体异常。

**G1 释放门控**：

- 数据：HangCup/PlugInEthernet 按 episode 80/20 切分；训练集校准阈值，留出集评估。
- 指标：释放事件 precision/recall、释放时刻误差（帧）、误触发率（在非释放段触发）。
- 目标：recall ≥90%、时刻误差 ≤3 帧、误触发 <5%。
- 消融：只用速度 / 速度+关节稳定 / 速度+关节稳定+目标误差；RG-P vs RG-V。

**G2 冗余 IK**：

- 数据：PlugInEthernet 演示的 EE 目标；比较无先验 IK 与 TRP IK。
- 指标：IK 成功率、关节限位余量、肘部先验误差、单步求解时间。
- 目标：IK 成功率 ≥99%、限位违规下降 ≥20%、单步 <2 ms（CPU）。

### 6.2 仿真（G3）

- 数字孪生：G1 URDF + Dex1 夹爪 + 桌面 + 5 个任务族；30Hz；注入 0/50/100/150 ms RTT。
- 变体：
  1. EE baseline（CHUNK-SERVO）；
  2. EE + RG；
  3. joint + RG；
  4. joint + RG + TRP。
- 任务：HangCup、StackBowls、PlugInEthernet、ZipUp、FoldTowel；每格 10 次，先做 5×4×2×10=400 的 pilot（两个延迟档），再按方差扩样。
- 指标：成功率、time-to-place、释放时刻误差、超时率、恢复时间。

### 6.3 真机单任务（G4）

- 单任务不计分通道；5 任务 ×10 次 ×3 变体（EE baseline、EE+RG、joint+RG）=150 trials。
- 指标：成功率、释放时刻误差、失败模式（早释放/晚释放/撞倒/未对准/超时）。
- 通过标准：placement 任务绝对成功率 +10%；非 placement 任务回退 ≤5%；joint 的 IK/限位失败率 <1%。

### 6.4 正式提交（G5）

- 只有 G4 通过才烧 320 trials；根据 A/B 选全局 joint 或 ee。
- 提交节奏：先 1 次全量看失败分布，再决定是否调阈值；不要连续盲提交。
- RG 默认开启；如果全量显示 RG 在非 placement 任务误触发，按任务族关闭/调阈值。

### 6.5 统计

- 每任务 10 次，成功率的 95% Wilson 区间很宽（例如 7/10 约 39–89%）；不要用单任务一次结果下结论。
- 用配对任务/多种子比较；预注册成功标准；把“释放时刻误差”作为连续指标，降低对二值成功率的依赖。
- 正式 320 trials 是最终证据；单任务 50–150 trials 只用于筛选。

## 7. 竞赛策略

### 7.1 任务组合

优先覆盖五种接触模式：

| 任务 | 模式 | 为什么优先 |
|---|---|---|
| T01 HangCup | 悬挂/释放 | 释放相位最清晰；本轮有 686 事件 |
| T27 StackBowls | 堆叠 | 放置高度/稳定性；释放后不能碰倒 |
| T26 PlugInEthernet | 插入 | 7-DoF 冗余最明显；本轮有 422 事件 |
| T19 ZipUp | 精细操作 | 小位移、高精度；测试关节空间稳定性 |
| T16 FoldTowel | 可变形 | 视觉对准 + 释放时机；测试泛化 |

### 7.2 预算

- 单任务不计分：5×10×3=150 trials；先跑 EE baseline / EE+RG / joint+RG。
- 正式：320 trials ×1–2 次；不要用正式 trials 做未验证的 A/B。
- 工程时间：G0 1–2 天；G1/G2 2–3 天；G3 2–3 天；G4 3–5 天；G5 1 周。

### 7.3 提交节奏

1. G0 通过后，先用 EE+RG 跑 1 个任务，确认 API/延迟/门控不崩。
2. 单任务通道跑 5 任务 ×3 变体；选 joint 或 ee。
3. 全量提交 1 次，记录失败模式；只调阈值/门控，不改模型。
4. 若 joint 在全量显示回退，回退 EE+RG；RG 是跨动作空间的稳定收益。
