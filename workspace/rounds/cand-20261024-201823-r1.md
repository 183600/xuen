# 第 1 轮（承接第 7 轮）· TABLE：桌面结构、预训练经济学、成本治理

> 检索/复核日期：2026-10-24（UTC）。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮承接第 7 轮 PILOT-GPR 的“终局放置是闸门”判断，但把视角从“放置专项”提升到“桌面原生系统”：**30% 的 ceiling 不是模型规模问题，而是最后一公里的系统问题——桌面的关系结构没有被显式表示、终局精度没有用系统手段买、昂贵的 3D/世界模型算力没有按成功价值分配。** 三个灵感词分别对应三把刀：桌面操作 → 关系化任务图 + 桌心坐标系；预训练 → 数据/精度缩放律告诉我们“别在预训练规模上硬拼”；成本控制 → 成功率先行 + 计算治理 + 用系统换精度。

## 0. 本轮先核实：规则与榜单的六个关键事实

### 0.1 排名规则：成功率先行，步骤分只是 tie-break

参赛手册（[S1][S2]）明确：每个任务 10 次独立运行，5 类泛化各 2 次；**实时榜单按 32 个任务的总平均成功率排序，成功率相同才按总平均步骤分排序，仍相同则早提交者靠前**。

这修正了第 7 轮的一个隐含假设（当时把成功率与步骤分当“综合排序”）。新的目标函数是：

```text
主目标 = 32 任务 × 10 次 = 320 trials 的全任务成功率
次目标 = 步骤分（只在成功率打平时使用）
```

含义：

- 终局放置仍然是 32/32 任务的成功闸门，所以“闸门”论点更强，不是更弱；
- 但“终局步骤占 39.8% 步骤分”不再能直接换算成排名收益——部分分只在 tie-break 时有用；
- 因此预算应从“提高步骤分”转向“把 episode 推到全成功”，并优先修复那些“只差最后一步”的失败。

### 0.2 每个任务 10 次、5 轴各 2 次、单次 180 秒

手册（[S1][S2]）：位置、干扰物、桌面背景、未见物品、人为干扰五类，每类 2 次；单次真机执行最大 180 秒，超时失败。每任务得分 = 10 次平均；总榜 = 32 任务平均。

统计后果：

- 320 trials，p≈0.30 时 SE≈2.56pp；+3pp 只有 1.2 SE，+5pp 约 1.95 SE。**2–3pp 的“提升”很可能是噪声**；
- 每任务成功率是 10% 量化的（0/10, 1/10, …）；总榜是 0.3125pp 量化；
- +5pp 总榜 = 多 16 次全成功；+10pp = 多 32 次。这个算术应写进每个实验的 Go/No-Go。

### 0.3 榜单仍是占位，不能用来判断谁强谁弱

`leaderboard.html` 仍是模糊 + “Coming Soon” 遮罩；`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`；`runs.html` 仍是 256/256 占位（[S3][S4][S5]）。占位榜的 8 个模型（MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、PI-0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%）**不是真实成绩**，只能当“头部也在 30% 以下”的结构先验（与用户给定前提一致）。

但模型名称对应的公开技术报告是真实的，可以用来看“头部做法与瓶颈”（§2）。

### 0.4 32 任务评分步骤仍公开；终局步是 32/32 的闸门

复核 T27/T10 的 `info.json`（[S6]）：`score_steps` 仍是 30/30/40；终局步骤是“把碗 3 叠到碗 2 上”/“把插头插到插排中”。第 7 轮的全量统计保持：终局步骤合计 1275/3200 = 39.8%；放置/插入/堆叠/闭合类约 59.7%；32 个终局里 28 个是放置类，4 个是拔出/取出/翻转/倾倒类。

### 0.5 数据仍是 32×~1k、约 33k、169h，2026-10-14 全量

HF collection 32 个数据集；HangCup 1,043 条/194,564 帧、StackBowls 979/295,609、PlugCharger 1,022/463,451；30fps；四路相机 `head_stereo_left/right` + `wrist_left/right`；EE 位姿 base/torso 两套；5 条英文复述（`meta/tasks.parquet`，[S7][S8]）。数据集 `lastModified` = 2026-10-14。

### 0.6 提交接口 v2 允许的观测/动作自由度没变

`unibot_submission` README（[S9]）：4×RGB 480×640、双臂 joint/EE、夹爪、下半身、单字符串语言；`obs_delta_indices` 选键+堆叠、`image_resize`、`action_chunk_size`、joint/ee 互斥；`reset()` 每 episode 一次。**观测裁剪、时序堆叠、分辨率、chunk 长度、EE 空间动作都在接口内。**

## 1. 三个灵感词，各钉到本轮事实上

### 1.1 桌面操作：不是“背景板”，是“关系结构 + 度量精度”

32 个任务里，大量目标不是“把 A 放到 B 附近”，而是关系性的：

- 左右/中间/顺序：T06 红绿黄从右到左、T15 工具从右到左、T21 盘子红绿蓝从右到左；
- 匹配/分类：T04 水果按颜色、T24 食物按类别；
- 堆叠/嵌套：T20 两下一上、T27 红绿蓝叠碗、T25 杯子进架；
- 拼写/字母：T22 拼 “robot”；
- 插入/闭合：T10 插头、T26 网线、T18/T19/T23/T31 拉链。

这意味着两件事：

1. **任务逻辑可以被符号化**：把每任务写成“关系目标图”（对象、关系、顺序、颜色/类别），语言只负责选图；位置泛化只改变坐标，不改变关系。当前端到端 VLA 把语言、关系、像素、动作纠缠在一个大模型里，OOD 位置/背景一来就崩；显式关系层是更便宜的归纳偏置。
2. **终局精度是度量问题**：插入/堆叠/拉链的间隙是毫米级；精度缩放律（[S12]）说，接近系统精度极限 c 时，所需演示数 N 随 log(N) ∝ 1/(P−c) 超指数增长。**用更多数据买 1mm 精度是下策；用腕部相机、视觉伺服、柔顺控制降低 c 才是上策。**

### 1.2 预训练：数据/精度缩放律说“别在规模上硬拼”

两条 2026 年证据：

- **数据缩放律**（[S11]）：跨 40k 演示、15k 真机 rollout 的研究发现，泛化随“环境数/物体数”呈幂律，**环境/物体多样性远比每个环境的演示数重要**；每个环境/物体超过阈值后，再加演示几乎没用。4 个数采员一个下午的数据，足以让两个任务在新环境/新物体上达到约 90%。
- **精度缩放律**（[S12]）：要达到固定成功率，所需演示数随目标精度 P 接近系统极限 c 而超指数增长；**c 不是物理常数，而是整个 agent 系统（传感器、专家策略）的属性**；加腕部相机或更好的专家可以降低 c。

对 UniBot 的直接含义：

- 官方 33k 是“每任务 ~1k、但环境/物体覆盖有限”的数据；继续在这 33k 上堆预训练/微调，边际收益递减；
- 真正缺的是**环境/物体多样性**和**系统级精度**，不是更多同分布演示；
- 头部模型（MolmoAct 2、WALL-OSS、DreamZero、GigaBrain-0）已经在“大规模预训练”上投入巨大；我们不该在同一个维度上比规模，而应该在**桌面结构、终局闭环、数据多样性**上比效率。

一句话：**不要 out-pretrain，要 out-structure + out-close-loop。**

### 1.3 成本控制：成功率先行、计算治理、用系统换精度

成本控制在本赛里有四层：

1. **评估成本**：320 trials 的统计噪声大；2–3pp 的提升不可信。把预算押在“能改变 ≥5pp 或能修复一整类失败”的干预上。
2. **数据成本**：精度数据超指数贵；多样性数据便宜且高杠杆。先做“一个下午 × 4 数采员 × 2 任务”的多样性补采，而不是大规模同分布采集。
3. **算力成本**：不自研 6B 预训练；用开放底座（WLA-1.0-Base 6B Apache-2.0，24GB 可微调；WALL-OSS-0.5 4B；MolmoAct 2）做 LoRA + 新头；小动力学模型（<10M 参数）做终局验证；昂贵的 3D/世界模型只在终局/高不确定步调用。
4. **推理成本**：动作 chunk + 事件触发重规划 + 自适应深度/弹性查询；目标 p99 <100ms 的 cheap path，昂贵路径 ≤10–20% 的步。

## 2. 榜单头部方案的做法与瓶颈（基于公开技术报告，非占位数字）

| 模型族 | 公开做法/能力 | 公开瓶颈 | 对 UniBot 的推断 |
|---|---|---|---|
| MolmoAct 2（VLA + 3D 推理） | Molmo 2-ER 骨干 + flow matching action expert；自适应深度 token；180ms 基础/790ms 深度；MolmoBot 20.6%、简单真机 87.1%（[S13]） | **一次规划 10–30 个动作的开环 batch，中途不重规划**；只对 SO-100/YAM/Franka 等训练过的形态开箱即用，人形/灵巧手需额外训练（[S13]） | 人形 + Dex1 的形态差、终局毫米级修正、人为干扰下的中途重规划是主要丢分点 |
| WALL-OSS-0.5（4B VLA） | 20+ 形态、1M+ 轨迹/epoch、梯度桥接 co-training；预训练本身有零样本行为；微调后 60.5% task progress，比 π0.5 +17.5%（[S14]） | task progress ≠ 全任务成功；终局精度/长程收尾仍是瓶颈 | 预训练解决“会不会”，不解决“最后 3cm 准不准” |
| DreamZero（14B WAM） | 视频扩散骨干联合预测未来视频+动作；2× 泛化于 VLA；7Hz 实时闭环；30 分钟 play data 适配新形态（[S15]） | 14B 视频模型训练/推理成本高；7Hz 低于 30Hz 控制；视频预测不保证任务成功 | 世界模型强在泛化，弱在精度/实时/成本；适合做“终局结果预测器”而非全时控制器 |
| GigaBrain-0（世界模型造数据） | 37.3k 小时异构数据；RGBD + 具身 CoT；世界模型生成 video/real2real/human/sim2real 数据（[S16]） | 生成数据与真实的 gap；数据生成成本；终局精度 | 数据多样性方向正确，但“造数据”不是我们的低成本优势 |
| π0.5 / GR00T N1.5 | 通用 VLA / 人形基础模型 | 形态适配、精度、OOD 轴 | 头部同质化：都在“更大预训练 + 更强泛化”，没人把“桌面关系 + 终局闭环”做成系统 |

**共同瓶颈（假设，待真机验证）**：

1. 开环 action chunk：遇到人为干扰/移动目标/碰撞，不能中途修正（MolmoAct 2 公开承认）。
2. 形态差：G1 + Dex1 不在多数模型的“开箱形态”里；微调后仍受数据覆盖限制。
3. 终局精度：插入/堆叠/拉链的毫米级容差，靠模仿学习的数据 scaling 很贵。
4. 关系逻辑：左右/顺序/匹配/拼写被隐式学习，位置/背景一变就失效。
5. 成本：14B 视频世界模型/6B VLA 全时运行，推理成本高，难以做多次重试/验证。

**结论：30% ceiling 是“最后一公里系统”问题，不是“再大 10× 预训练”问题。**

## 3. 本轮主判断：桌面原生分解（TABLE-GPR）

### 3.1 一句话

**把 32 个任务分解成“关系任务图（RTTG）+ 桌心对象状态（TCS）+ 终局系统精度（PBS）+ 事件触发纠错（GEC）”，用共享骨干的多个头实现单模型合规；预训练只做“桌面动力学头”的轻量自监督，不在规模上硬拼；成本治理按“成功价值/计算成本”分配昂贵模块。**

### 3.2 为什么这比第 7 轮更进一步

第 7 轮把火力集中在“终局放置”，仍然是在端到端 VLA 外面加 PGL/OPT/SVL。本轮认为：

- 终局放置只是“最后一公里”的一部分；**关系逻辑错误**会让 episode 根本到不了终局（选错对象/顺序/槽位）；
- **开环 chunk** 会让人为干扰/移动目标直接失败，即使终局放置很强；
- **精度**不是靠更多演示，而是靠腕部伺服/柔顺/落点校验；
- 因此需要把“桌面任务”整体分解，而不是只修终局那一步。

### 3.3 与第 7 轮资产的关系

- 保留：SSG（升级为 RTTG 的评分步骤子图）、PGL/OPT（并入 TCS/PBS）、ICR（改为 canonical retrieval）、NRB（并入 GEC 的恢复库）、DebugLoop、FLEET 工程检查单。
- 升级：SVL → PBS（精度系统）；RB → NRB + GEC；L2L → DTD（轻量多样性数据飞轮，不再先建大实验室网络）。
- 新增：RTTG、TCS、OSD、GEC、SFA、FFC。
- 修剪：步骤分优先的预算逻辑；6B 从零预训练；全 32 任务高保真孪生；自由仿真数据；运行时 MPC/RL；每任务 LoRA。

## 4. 方案轮廓

```text
语言（32×5 复述）
   │
   ▼
RTTG 关系任务图：对象/关系/顺序/颜色/类别 + 官方 score_steps
   │  （符号规划器：选对象 → 选槽位 → 排序 → 生成 pick/place 子目标）
   ▼
TCS 桌心对象状态：桌面平面 + 对象 slot（位姿/尺寸/类别/可抓性）+ 关系边
   │  （共享骨干的多个头：slot 头、平面/深度头、谓词头、不确定性头）
   ▼
GEC 计算治理：cheap path（策略头 + 长 chunk） vs expensive path（3D/动力学/检索/验证）
   │  触发：终局步、谓词不匹配、视觉偏差、人为干扰、移动目标
   ▼
PBS 终局系统精度：槽位→2D 锚点→6D 位姿（演示统计）+ 腕部视觉伺服 + 柔顺插入 + 缓放/稳定校验
   │
   ▼
执行 / 监控 / 重试 / 恢复（NRB 官方备注剧本）
```

### 4.1 RTTG：关系任务图

- 每个任务一个图：`objects → relations → ordered subgoals`；例如 T06：`rightmost=red, middle=green, leftmost=yellow`；T22：`spell("robot")`；T27：`stack(red, green, blue)`。
- 语言解析：32×5 复述精确匹配 + 规范化 + 嵌入兜底；不需要通用 LLM 也能跑；LLM 只在离线建图时用。
- 规划器：把关系目标转成“抓谁、放哪个槽、什么顺序”；位置泛化只改坐标，不改关系。
- 与 VLA 的关系：VLA 仍是执行器；RTTG 提供子目标/约束，不硬编码低层轨迹。若规划器置信度低，回退到端到端 VLA。

### 4.2 TCS：桌心对象状态

- 桌面坐标系：原点在桌面前沿中心，z 向上，x 向前，y 向左；用单目深度/平面拟合 + 机器人基座/EE 先验估计。
- 对象 slot：任务相关物体 + 容器/架子/槽位；每个 slot 有 3D 中心、朝向、尺寸、类别、可抓性、材质（刚体/布料/透明）。
- 关系边：on/in/left/right/front/back/stack/contain；用几何规则 + 学习头。
- 实现：共享骨干 + slot 头/平面头/关系头；尽量不引入独立大模型，保持“单模型”合规。

### 4.3 OSD：对象中心稀疏动力学预训练

- 用 33k 演示自监督训练一个**稀疏残差动力学头**：输入当前 slot 状态 + EE 动作，输出“哪些 slot 会动 + delta 位姿”；静态对象直接复制。
- 证据：稀疏残差世界模型在桌面 pushing 上比 dense MLP 准 2.5–4.6×、参数少 8.6–11.1×、1/4 数据达 90% 精度（[S17]）。
- 用途：
  1. 终局放置前 rollout 候选位姿，预测稳定性/关系是否满足；
  2. 生成状态级反事实（移动容器/对象），训练策略头的位置泛化；
  3. 作为辅助损失，让共享骨干学到桌面物理。
- 限制：只对刚体/容器可靠；布料/拉链/透明走“相位检索 + 策略先验”，不用 OSD 做 rollout。

### 4.4 GEC：事件触发纠错 + 计算治理

- **cheap path**：共享骨干 + 策略头，缓存视觉特征，长 action chunk（16–32），30Hz 执行。
- **expensive path**：额外深度/3D、OSD rollout、canonical retrieval、谓词验证；只在以下情况调用：
  - 终局步/高权重步；
  - 不确定性头高（ensemble/特征偏差）；
  - 谓词从 1→0（人为干扰/物体被拿走）；
  - 视觉动态偏差（VLA-Corrector 式 latent monitor，[S18]）；
  - 移动目标（T24）。
- **价值-计算规则（VoC）**：

```text
VoC(m, s) = P(失败 without m) × P(m 能修复) × w_s / cost(m)
w_s = 1.0 若 s 是成功闸门/终局步；0.2 若只是中间步骤分
选择 argmax VoC(m,s)，若 VoC > 阈值才升级
```

- 参考：EQRL 的弹性查询（自适应 latent/denoising/chunk，不微调底座，[S19]）；EMS 的双系统稀疏调用慢系统（[S20]）；VLA-Corrector 的偏差检测+截断重规划（[S18]）。
- 单模型合规：GEC 是确定性控制器 + 同一 checkpoint 的不同头，不是多模型集成。

### 4.5 PBS：用系统买精度

- 终局目标三级：槽位/区域（RTTG）→ 2D 锚点（头/腕相机渲染）→ 6D 位姿（演示统计中位数 + 离散度）。
- 腕部视觉伺服：用腕部相机把相对位姿误差压到毫米级；对插入类任务，先对准再柔顺推进。
- 柔顺/力控：插入/拉链/插头用低刚度/阻抗控制，避免硬撞；用夹爪开度/电流/视觉反馈判断到位。
- 缓放 + 稳定校验：释放后 0.5s 内位移 <ε 且谓词保持才算完成；失败则 nudge/regrasp/retry（≤2 次，长程任务 ≤1 次）。
- 精度账本：每任务记录“要求精度 P*、系统极限 c、数据成本、系统改造成本”，优先做“c 可降、P* 不太远”的任务。

### 4.6 DTD：多样性数据飞轮（轻量）

- 数据缩放律说环境/物体多样性 > 演示数；不需要大实验室网络，先做“1 实验室 × 2 任务 × 一个下午 × 4 数采员”的试点（约 400–800 条）。
- 目标：补背景/位置/未见物品三轴；每任务 100–200 条，场景/物体多样，不追求同分布数量。
- 合成数据：TableVerse-100K（100k 场景、~1M 物体、35k 类别、CC BY 4.0，[S21]）可用于**桌面状态/动力学头的预训练**或背景/布局增强；但合成不主导，且需规则允许。
- 合规开关：外部数据默认 OFF；先邮件确认；若禁止，DTD 只做赛后研究，主方案仍可在官方 33k 上跑。

### 4.7 SFA：成功率先行分配器

- 榜单按成功率排序；步骤分只 tie-break。因此：
  - 不做“只提步骤分”的优化；
  - 优先修“到终局但失败”的 episode（如果 q 高）；
  - 优先修“一整类任务”的共同失败（关系逻辑/精度/干扰），而不是单任务特调；
  - 用 320 trials 的统计功效设定 Go/No-Go：目标 ≥5pp，或单任务 ≥2/10 的提升且可复现。
- 任务组合：按“失败率 × 可修复性 / 成本”排序；关系类（13）、精度类（7）、形变类（12）、人干扰（全任务 20% trials）。

### 4.8 FFC：冻结基础模型 + 小头（可选）

- 如果规则/算力限制不允许大模型微调：冻结 WLA/MolmoAct/WALL-OSS 骨干，只训 slot/关系/策略/动力学头（LoRA + heads）。
- 成本：单卡 24GB 可跑；迭代快；适合先验证 RTTG/TCS/PBS 的增益，再决定是否全量微调。
- 风险：容量/分布匹配；如果小头明显弱于全量微调，回退到 LoRA 全量。

## 5. 风险与合规（先立后破）

- **单模型边界**：RTTG 是确定性代码；TCS/OSD/GEC/PBS 是同一 checkpoint 的多个头；不按任务切换模型。模型卡写清所有学习组件；若官方认定冻结感知模型也算多模型，改用共享骨干内部特征，不引入独立大模型。
- **外部数据/预训练权重**：手册只读到“提供 32 任务数据”，外部数据/合成数据/预训练权重是否允许**未核实**；默认 OFF，邮件确认后再开。核心方法（RTTG/TCS/GEC/PBS）不依赖外部数据。
- **关系规划器脆性**：32 任务是封闭集，5 条复述已知；用精确匹配 + 嵌入兜底；规划置信度低时回退端到端 VLA；不让规划器硬控低层。
- **透明/布料/拉链**：slot/OSD 不可靠；这些任务只用相位检索 + 策略先验 + PBS 的腕部伺服，不做全物理。
- **计算治理复杂度**：先规则化 VoC，阈值离线校准；监控误触发率；保留“全 cheap”和“全 expensive”两个降级档。
- **统计噪声**：320 trials；目标 ≥5pp；配对种子/bootstrap；不把 1–2pp 当胜利。
- **时间**：180s/任务；GEC/PBS 的重试预算 ≤2 次（长程 ≤1 次）；总时长守卫。

## 6. 一句话押注

**押“桌面原生分解”：30% 的 ceiling 是最后一公里系统问题——用关系任务图把任务逻辑从像素里拿出来，用桌心对象状态把位置/背景/干扰因素结构化，用事件触发纠错和腕部精度系统把最后 3cm 做闭环，用计算治理只在高价值步花大算力；这比再堆 10× 预训练更便宜、更可解释、更可能把成功率推过 30%。**

## 1. 事实核对（本轮新增/复核；来源表见 §11）

### 1.1 规则：成功率先行、10 次/任务、5 轴各 2 次、180 秒

参赛手册（[S1][S2]）原文要点：

- 仅设 **多任务通才模型赛道**；必须单模型完成全部 32 任务；不得混合多个模型按任务切换；模型类型不限（World Model、VLA 均可）。

- 单次真机执行最大 **180 秒**，超时失败；按执行情况计算步骤分。

### 2.2 共同瓶颈

1. **开环 action chunk**：MolmoAct 2 公开承认“plan a batch of 10–30 moves and execute the whole sequence without inferring again”；遇到人为干扰、移动目标（T24）、碰撞，不能中途修正。UniBot 的 human 轴是 2/10 trials，正好打这个弱点。
2. **形态差**：G1 + Dex1 不在多数模型的“开箱形态”里；MolmoAct 2 明确说 humanoid/hand-equipped 需额外训练。官方 33k 是 G1 数据，微调可缓解，但终局精度仍受数据覆盖限制。
3. **终局精度**：插入/堆叠/拉链的毫米级容差；精度缩放律说数据成本超指数，单靠模仿学习 scaling 不划算。
4. **关系逻辑**：左右/顺序/匹配/拼写被隐式学习；位置/背景一变就失效。端到端 VLA 没有显式关系变量。
5. **成本**：14B 视频世界模型/6B VLA 全时运行，推理成本高，难以做多次重试/验证；7Hz 控制率也限制闭环。

### 2.3 为什么 30% 是系统问题

- 32 个终局里 28 个是放置/插入/堆叠/闭合；这些是**成功闸门**，但头部模型在“开环 + 形态差 + 精度”上同时丢分。
- 5 个泛化轴里，位置/背景/干扰物/未见物品都可以用**显式桌面状态**部分因子化；人为干扰可以用**事件触发纠错**处理。头部模型把这些都交给一个大模型隐式学习，OOD 一起来的组合拳就会崩。
- 因此，提升路径不是“再大 10× 预训练”，而是“把最后一公里做成系统”：关系层、状态层、精度层、纠错层。

## 3. 成本/精度/统计算术

### 3.1 成功率优先与 320 trials

```text
32 tasks × 10 runs = 320 trials
p ≈ 0.30 → SE = sqrt(0.30×0.70/320) ≈ 2.56pp
+3pp ≈ 1.17 SE；+5pp ≈ 1.95 SE
每任务 10 trials → 成功率量化 10%；总榜量化 0.3125pp
+5pp 总榜 = 16 次全成功；+10pp = 32 次
```

- 目标 ≥5pp；2–3pp 的提升需要更多 trials 才能可信（80% power 检测 3pp 约需 3,700 trials，不现实）。
- 因此优先“改变一整类失败”的干预（关系/精度/干扰），而不是单任务微调。
- 步骤分只在成功率 tie-break 时有用；不要为步骤分做高风险优化。

### 3.2 终局闸门杠杆

对单终局任务：

```text
P(success) ≈ q × p_t
q = P(到达终局步)；p_t = P(终局步成功 | 到达)
```

- 若 q≈0.6，p_t +10pp → 总成功率 +6pp；若 q≈0.5 → +5pp。
- 终局放置跨五轴同时起作用；单轴 +10pp 只贡献 +2pp（该轴 2/10 trials）。
- 关系/状态层主要提高 q（让 episode 到终局）；PBS 主要提高 p_t；GEC 同时提高 q/p_t（干扰/移动目标）。

| 干预 | 主要作用 | 作用范围 | 粗略总增益 |
|---|---|---|---|
| RTTG+TCS | q（选对对象/槽位/顺序；位置/背景因子化） | 关系类 13 任务 + 全任务位置/背景轴 | +3–6pp（假设） |
| PBS | p_t（毫米级终局） | 精度类 7 任务 + 所有放置终局 | +3–5pp（假设） |
| GEC | q/p_t（干扰/移动目标/偏差） | human 轴 20% + T24 | +3–5pp（假设） |
| DTD | q/p_t（未见物品/背景） | unseen/background 40% trials | +2–4pp（假设） |

这些是假设，必须用离线诊断 + 调试槽校准；不要叠加宣传。

### 3.3 精度缩放律与精度账本

精度缩放律（[S12]）：`log(N) ∝ 1/(P − c)`；N=所需演示数，P=目标精度，c=系统精度极限。c 是系统属性；加腕部相机/更好的专家可降低 c。

**精度账本（作者估计，非官方）**：

| 桶 | 任务 | 估计要求 | 系统策略 | 数据策略 |
|---|---|---|---|---|
| 高精度（≤2mm） | T05, T10, T12, T19, T26, T31, T32 | 插头/网线/钥匙/拉链/针筒 | 腕部视觉伺服 + 柔顺/阻抗 + 到位判定 | 少量高质量演示 + 在线伺服，不堆数据 |
| 中精度（2–10mm） | T01, T07, T13, T18, T20, T21, T23, T25, T27, T28, T29 | 挂钩/相框/试管/叠杯/叠碗/装盒 | 2D 锚点 + 6D 位姿统计 + 缓放/稳定校验 | 演示统计 + 少量失败恢复 |
| 低精度（>10mm） | T02, T03, T04, T06, T08, T09, T11, T14, T15, T16, T17, T22, T24, T30 | 收集/分类/摆放/倾倒/拼写 | 关系规划 + 策略执行 | 多样性数据优先 |

**结论**：高精度任务不要用“更多演示”硬买；用 PBS 的系统手段降低 c。中精度任务用演示统计 + settle verify。低精度任务用 RTTG/TCS 提高 q。

### 3.4 数据缩放律与 DTD

数据缩放律（[S11]）：40k 演示、15k 真机 rollout；泛化随环境数/物体数幂律；**多样性 >> 每环境演示数**；4 个数采员一个下午的数据可让两个任务在新环境/新物体上约 90%。

**DTD 试点**：

- 1 个有 G1 的实验室 × 2 个任务（建议 T27 叠碗 + T10 插头，覆盖放置/插入）× 一个下午 × 4 数采员 ≈ 400–800 条。
- 场景/物体多样：不同桌布、背景、光照、物体颜色/形状、初始位置；每任务 100–200 条。
- QA：四路同步、30fps、动作平滑、夹爪事件、步骤覆盖、5 条复述匹配；人工抽检 10%；单批拒绝率 >20% 停采。
- 合规：外部数据默认 OFF；邮件确认后开；若禁止，DTD 只做赛后研究。
- 成本：远低于大规模同分布采集；符合“成本控制”。

### 3.5 计算/延迟预算

| 项 | 估计 | 说明 |
|---|---|---|
| cheap path | 6B VLA ~180ms/query（MolmoAct 2 参考）；chunk 16–32 @30Hz → 每 0.5–1s 一次 query | 单卡可跑；缓存视觉特征 |
| expensive path | +300–800ms（深度/3D/OSD rollout/检索/验证） | 只在终局/高不确定步；≤10–20% 步 |
| 单 trial | 180s × 30Hz = 5,400 steps；chunk 16 → ~338 queries；180ms → ~61s GPU | 320 trials ≈ 5.4 GPU-hours（cheap）；若 790ms ≈ 24 GPU-hours |
| 训练 | LoRA 8×H100 2–3 周；头/OSD 各 1–2 GPU 天 | 远低于从零 6B 预训练 |
| 数据 | 官方 33k 免费；DTD 400–800 条；合成可选 | 标注 2–3 人 |

**成本控制结论**：推理成本不是主要瓶颈；主要成本是训练/数据/评估。用开放底座 + LoRA + 小头 + 轻量 OSD，避免从零预训练；用 DTD 小规模多样性补采，避免大规模同分布采集；用成功率统计功效避免无效实验。

### 3.6 预算分配（修订第 7 轮）

```text
关系/状态（RTTG+TCS）        30%
终局精度（PBS）              30%
纠错/干扰（GEC+NRB）         20%
数据/动力学（DTD+OSD）       20%
```

工程/部署（DebugLoop、FLEET 检查单）作为发布门，不占研究预算；但每次大版本预留 1 个调试槽。

### 4.2 RTTG：关系任务图

**输入**：语言复述（32×5=160 条）+ 官方 score_steps + 场景图。

**图结构**：

```text
TaskGraph:
  objects: [obj slots / receptacles / tools]
  relations: [left_of, right_of, middle, on, in, stack, match_color, match_category, spell]
  order: partial order of subgoals
  score_steps: official steps + weights
```

**例子**：

- T06：`slot(leftmost)=yellow, slot(middle)=green, slot(rightmost)=red`；顺序：red → green → yellow（从右到左放置，避免碰撞）。
- T22：`spell("robot") = [b, o, t]`（官方步骤是 b/o/t；语言可能只给 "spell robot"）。
- T27：`stack([red, green, blue])`；顺序：red 中间 → green 叠 red → blue 叠 green。
- T21：`order(right_to_left)=[red, green, blue]` into rack。
- T24：`category(food)` → rack position；移动目标用 GEC 跟踪。

**规划伪代码**：

```python
def plan(task, scene, step_state):
    g = TASK_GRAPHS[task]                  # 官方 score_steps + 关系
    bindings = ground(g, scene)            # 场景图绑定对象/槽位
    if bindings is None:                   # 感知不确定
        return fallback_to_vla(task, scene)
    subgoals = topological_order(g, bindings)
    sg = subgoals[step_state]
    return Subgoal(pick=sg.obj, place=sg.slot, relation=sg.rel,
                   anchor=project(sg.slot, scene), pose=pose_prior(sg))
```

**与 VLA 的分工**：RTTG 只给“抓谁/放哪/什么顺序/什么关系”；低层轨迹仍由策略输出。规划置信度低 → 回退端到端；规划器不硬控关节。

### 4.3 TCS：桌心对象状态

**坐标系**：原点在桌面前沿中心，z 向上，x 向前，y 向左；单位米。用单目深度/平面拟合 + 机器人基座/EE 先验估计；每 episode reset 时校准一次，之后用 EE/视觉跟踪更新。

**对象 slot**：

```python
Slot = {
  id, category, mask, xyz, quat, extent, grasp_affordance,
  material: rigid | deformable | transparent | articulated,
  container: bool, opening_normal, capacity
}
```

**关系边**：`on(a,b)`, `in(a,b)`, `left_of(a,b)`, `right_of(a,b)`, `front_of`, `behind`, `stack(a,b)`, `match_color(a,b)`, `match_category(a,b)`。几何规则 + 学习头；透明/布料用 2.5D mask + 相位标签，不强求 6D。

**实现**：共享骨干 + 头：

- plane head：桌面平面/法向；
- slot head：mask + 3D center + extent（可先用伪标签训练）；
- relation head：关系分类；
- predicate head：步骤完成谓词；
- uncertainty head：动作/状态不确定性。

**单模型合规**：所有头共享同一骨干、同一 checkpoint；不引入独立大模型。若必须用外部检测器，优先用骨干内部特征；模型卡披露。

### 4.4 OSD：对象中心稀疏动力学预训练

**动机**：桌面场景变化稀疏；只预测会动的 slot，比 dense 世界模型更准、更省。证据：稀疏残差模型 2.5–4.6× 精度、8.6–11.1× 少参数、1/4 数据达 90%（[S17]）。

**模型**：

```python
def osd_step(slots, action):
    gate = sigmoid(gate_head(slots, action))       # [N] 哪些 slot 会动
    delta = delta_head(slots, action)              # [N, 7] xyz+quat delta
    return slots + gate[:, None] * delta
```

- 参数 <10M；输入 slot 特征 + EE action；输出 gate + delta。
- 训练：33k 演示的 next-slot 预测；伪标签来自 TCS 跟踪；静态 slot 复制；辅助关系转移分类。
- 用途：
  1. **终局 rollout**：候选放置位姿 → 预测 0.5s 后 slot 状态 → 稳定性/关系是否满足；
  2. **反事实**：移动容器/对象，生成状态级训练对；
  3. **辅助损失**：让共享骨干的特征包含桌面物理。
- 限制：刚体/容器可靠；布料/拉链/透明不做 rollout，只用相位检索 + 策略先验。

### 4.5 GEC：事件触发纠错 + 计算治理

**两条路径**：

```python
def act(obs, task, step_state, budget):
    state = tcs_head(obs)                      # 每步或每 k 步
    sg = rttg.next_subgoal(task, state, step_state)
    uncertain = uncertainty_head(state) > tau_u
    terminal = rttg.is_terminal(step_state)
    lost = predicate_head(state, step_state) < 0.5
    moving = task in MOVING_TASKS or visual_motion(obs) > tau_m
    if terminal or uncertain or lost or moving:
        plan = expensive_path(state, sg)       # 3D + OSD rollout + retrieval + verify
    else:
        plan = cheap_path(obs, sg)             # cached features + policy head
    chunk = policy.act(obs, plan)
    dev = latent_monitor(chunk, obs)           # VLA-Corrector 式
    if dev > tau_d:
        truncate_chunk()
        plan = expensive_path(tcs_head(obs), sg)
        chunk = policy.act(obs, plan)
    return chunk
```

**VoC 规则**：

```text
VoC(m, s) = P_fail(s) × P_fix(m, s) × w_s / cost(m)
w_s = 1.0 if terminal/success gate else 0.2
choose m with max VoC, if VoC > theta
```

- `P_fail` 由 uncertainty head/历史统计估计；`P_fix` 由离线回放/规则估计；`cost` 由延迟 profile 估计。
- 参考：EQRL 弹性查询（[S19]）、EMS 双系统稀疏调用（[S20]）、VLA-Corrector 偏差检测/截断（[S18]）。
- 单模型：GEC 是确定性控制器 + 同 checkpoint 的头；不按任务切模型。

**NRB 恢复**：官方 human 备注（表 B）转成破坏→恢复剧本：

| 任务 | 备注 | 恢复 |
|---|---|---|
| T27 | 叠了第二个之后拿下第二个 | 重新放 bowl2 → 继续 bowl3 |
| T19 | 拉上拉链之后拉开 | 重新拉合 |
| T14 | 拧开盖子之后拧动回来 | 再拧开 → 倒药 |
| T17 | 笔盒合上之后手动打开 | 重新合上 |
| T24 | 可乐/薯片快到终点再放回起点 | 重新抓取→放置 |
| T10 | 将插头拔起 | 重新抓取→插入 |
| T12 | 中途把锁拿走 | 重新定位锁→继续翻环 |
| T02/T04/T11/T25 | 移动水果/盘子/底座 | 重新定位→继续当前步 |

备注编号含义未核实；即使不是精确评测剧本，也是分布内高价值扰动。

### 4.6 PBS：用系统买精度

**三级目标**：

1. **槽位/区域（RTTG）**：语义关系（leftmost/middle/on/in/stack）。
2. **2D 锚点**：把 6D 目标投影到头/腕相机，渲染十字 + 朝向 + 容差圈；训练/推理同渲染管线（防域差）。
3. **6D 位姿**：K 条演示的容器系释放位姿统计：

```text
H_i = (T_B^R)^{-1} · T_B^G(t_i^release)      # 容器系释放位姿
xyz = median_i(H_i.xyz)
rot = chordal mean of quaternions
sigma = std_i(H_i.xyz); sigma_theta = angular spread
target = T_B^R · H
```

**控制策略**：

- `sigma < τ1`：直接执行；
- `τ1 ≤ sigma < τ2`：慢速 + 腕部视觉伺服；
- `sigma ≥ τ2`：放弃迁移 → 锚点伺服 + 保守放置。
- 插入/拉链/插头：低刚度/阻抗 + 腕部相机对准 + 到位判定（夹爪开度/电流/视觉）。
- 释放：缓放 + 0.5s 稳定校验（位移 <ε 且谓词保持）；失败 → nudge/regrasp/retry（≤2 次；长程 ≤1 次）。

**精度账本**：每任务记录 P*、c、τ_task、数据成本、系统改造成本；优先“c 可降、P* 不太远”的任务（见 §3.3）。

### 4.7 DTD：多样性数据飞轮

- 试点：1 实验室 × 2 任务 × 一个下午 × 4 数采员 ≈ 400–800 条；场景/物体多样；每任务 100–200 条。
- 对齐官方 schema：LeRobot v3；`robot_type=unitree_g1`；30fps；四路相机同名；EE base/torso；5 条复述；步骤标签。
- 合成可选：TableVerse-100K（100k 场景、~1M 物体、35k 类别、CC BY 4.0，[S21]）用于 TCS/OSD 预训练或背景/布局增强；合成不主导。
- 合规：默认 OFF；邮件确认；QA/许可/署名。

### 4.8 SFA + FFC

**SFA（成功率先行分配器）**：

- 任务组合按 `失败率 × 可修复性 / 成本` 排序；
- 关系类 13、精度类 7、形变类 12、人干扰 20% trials；
- Go/No-Go 用 ≥5pp 或单任务 ≥2/10；不把 1–2pp 当胜利；
- 每次大版本 1 个调试槽；计分跑 1–2 次。

**FFC（冻结骨干 + 小头）**：

- 冻结 WLA/MolmoAct/WALL-OSS 骨干；只训 TCS/RTTG/策略/OSD 头（LoRA + heads）；
- 单卡 24GB 可跑；快速消融；若明显弱于全量微调，回退 LoRA 全量；
- 成本控制的核心备选：先验证“结构”增益，再决定是否花大算力。

## 6. 评测协议

### 6.1 三级评测

1. **离线（每天）**：关系/槽位/谓词 F1；桌面平面误差；释放位姿在 τ_task 内比例；OSD next-slot 误差；GEC 误触发率；延迟 p50/p99。
2. **本地（每周）**：离线回放/相对比较台；只做失败挖掘，不做模型选择；不做高保真孪生承诺。
3. **平台（版本门）**：不计分单任务调试槽；首选 T27（叠碗=关系+放置）、T10（插头=精度）、T24（移动目标）、T19（拉链=形变）。判定：终局步 ≥+10pp 且无回归才进计分跑；每个大版本最多 1 槽。

### 6.2 指标

- 主：32 任务平均成功率（320 trials）。
- 次：平均步骤分（tie-break）。
- 诊断：每任务每步完成率；五轴分解；终局条件成功率 `p_t`；到达终局率 `q`；延迟 p50/p99；GPU 成本；数据成本。
- 统计：配对种子/bootstrap 95% CI；目标 ≥5pp；不把 1–2pp 当胜利。

### 6.3 Go/No-Go

| 假设 | 测试 | 通过 | 失败 |
|---|---|---|---|
| RTTG+TCS 提升位置/背景 | 离线 OOD 诊断 + 调试槽 | ≥+3pp | 回退纯 VLA/只保留 PBS |
| PBS 提升终局精度 | T10/T27 调试槽 | ≥+5pp | 回退 SVL 简化版 |

## 8. 创新点清单（持续迭代；动机/差异/可行性/资源/步骤/风险/状态）

> 状态：押注=本轮主线；高=强候选；中=备选；保留=沿用；降级=保留但非主回路；砍=不做。

### I1 RTTG 关系任务图（新增，押注）

- **动机**：32 任务大量是关系性的（左右/顺序/匹配/拼叠/拼写）；端到端 VLA 把关系隐式学，位置/背景一变就崩。官方 score_steps + 5 复述已给出封闭集，可符号化。
- **差异**：头部模型（MolmoAct 2/WALL-OSS/DreamZero）是端到端 VLA/WAM；我们在外面加一层“关系任务图 + 符号规划”，策略只执行子目标。不是硬编码轨迹，规划置信度低可回退。
- **可行性**：32 任务封闭集；160 条复述；score_steps 公开；CPU 代码；无需新数据。
- **资源**：1 人周建图/解析；无 GPU；无接口改动。
- **步骤**：解析 info.json/复述 → 32 图 → 规划器 → 与策略头接线 → 离线回放 → 调试槽。
- **风险**：语言复述超出 160 条 → 嵌入兜底；规划器脆性 → 置信度回退；关系感知错 → TCS 校正。
- **状态**：押注。

### I2 TCS 桌心对象状态（新增，押注）

- **动机**：位置/背景/干扰物三轴的本质是“场景外观/坐标变了，关系没变”；桌心坐标系 + 对象 slot 把不变量显式化。
- **差异**：头部模型用 3D depth token/视频世界模型，但仍端到端；我们用共享骨干的多个头输出可解释的桌面状态，作为策略条件。
- **可行性**：四路相机 + EE 位姿；单目深度/平面拟合；slot 伪标签可半自动；共享骨干头不改接口。
- **资源**：1–2 人 × 3 周；单卡/8 卡；无额外数据（伪标签 + 抽检）。
- **步骤**：桌面平面 → slot 头 → 关系头 → 与 RTTG/PBS 接线 → OOD 诊断。
- **风险**：透明/布料/小件 slot 不稳 → 2.5D mask + 分桶回退；伪标签噪声 → 抽检/置信度。
- **状态**：押注。

### I3 PBS 终局系统精度（升级 SVL，押注）

- **动机**：终局是 32/32 闸门；精度缩放律说数据买精度超指数贵；腕部相机/伺服/柔顺能降低系统极限 c。
- **差异**：第 7 轮 SVL 是“放完校验”；本轮把“瞄准—插入—缓放—稳定”做成系统，并用精度账本选择任务。
- **可行性**：腕部相机已在观测里；EE 动作空间可用；180s 预算够 1–2 次重试。
- **资源**：1–2 人 × 2 周；无需新数据；需要真机/调试槽校准伺服增益。
- **步骤**：释放位姿统计 → 2D 锚点 → 腕部伺服 → 柔顺/到位 → settle verify → 重试。
- **风险**：腕部遮挡/透明 → 多视图/电流；力控参数 → 保守增益；耗时 → 预算守卫。
- **状态**：押注。

### I4 GEC 事件触发纠错 + 计算治理（新增，押注）

- **动机**：头部模型开环 chunk（MolmoAct 2 公开承认）；UniBot 有 human 轴 20% + 移动目标 T24；全时大模型推理贵。
- **差异**：不是“固定频率重规划”，而是“按成功价值/计算成本升级”；用 latent monitor + 谓词 + 不确定性触发；单 checkpoint 多头，不是多模型。
- **可行性**：VLA-Corrector/EQRL/EMS 已有公开证据；接口允许 chunk；延迟可测。
- **资源**：1–2 人 × 3 周；单卡 profiling；无需新数据（可用回放）。
- **步骤**：latent monitor → 触发规则 → VoC 阈值 → 截断/重规划 → 延迟压测 → 调试槽。
- **风险**：误触发/延迟 → 双阈值/降级档；复杂 → 先规则化；单模型审计 → 披露。
- **状态**：押注。

### I5 OSD 对象中心稀疏动力学（新增，高）

- **动机**：桌面变化稀疏；小动力学模型可做终局 rollout/反事实，比 14B 视频世界模型便宜得多。
- **差异**：稀疏残差 + slot 级预测（2.5–4.6× 精度、8.6–11.1× 少参数）；只做终局验证，不做全时控制。
- **可行性**：33k 演示；TCS 伪标签；<10M 参数；1–2 GPU 天。
- **资源**：1 人 × 2 周；1–2 GPU；无接口。
- **步骤**：slot 序列 → gate/delta 头 → next-slot 训练 → 终局 rollout → 反事实。
- **风险**：形变/透明失效 → 分桶不用；伪标签误差 → 置信度/抽检。
- **状态**：高。

### I6 DTD 多样性数据飞轮（升级 L2L，高）
