# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配多模态交互消歧闭环」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「开源软件」×「强化学习训练」）

> R69 教会系统「问」：把不确定性拆成 aleatoric / epistemic，用流匹配多模态策略显式表示歧义，用主动交互（看/问/触）去消解，用一次交互的似然与证据纪律兜底。但它留下两个**未经审查的前提**：
> 1. **它信任那个告诉它「该问什么」的东西**——一个单体流策略的模态分布被当作先验事实，只靠一个 ECE 门看守。若该模型幻觉出不存在的模态、或把真模态坍缩掉，R69 的全部 VoI 都在一个谎言上计算。这正是 R69 自陈的最大风险。
> 2. **它的交互技能、成本与阈值是手写的、冻结的**——它从不从「问过什么、得到什么」的日志里学习；也从不区分「一次回答」与「一条可被独立复现的证据」。
>
> 本轮两个灵感正好补上这两块：
> - **开源软件**回答「如何信任一棵巨大的依赖树」：不是相信某个供应商，而是**锁定版本、校验哈希、可复现构建、SBOM 溯源、语义化版本、代码评审、CI 门、fork**。信任从一种感觉变成一个**可验证的依赖闭包**。
> - **强化学习训练**回答「何时问、该信哪个模块、怎么组合」：从日志里离线学习策略。但它带来一个更隐蔽的敌人——**奖励黑客**，尤其是「学会如何骗过验证器」。
>
> 核心命题：**把 R69 的认知层重构为一个开源式的「证据供应链」——每个模态必须携带来源与契约，每个交互决策必须在一个经哈希锁定、契约可满足的依赖闭包上计算；RL 只能「在预先验证过的闭包之间选择」，并把任何改动作为补丁交给环路之外的评审，绝不在实时环路里改写验证本身。** 命名 **COMMONS-RAS**（Contract-checked Open-source Modules with Manifest-pinned Orchestration and No unsafe Substitution）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证、还能问什么」，R70 问「**告诉我该向谁求证的那个东西，本身可信吗、被谁审过**」——信任不是一个标量，而是一条供应链。

## 0. 直觉与动机

**灵感 1（开源软件 → 信任从「相信模型」变成「验证依赖闭包」）**
直觉：R69 的模态分布像一段从网上下载的、没有签名的二进制：你要么整体相信它，要么整体不信。开源软件早就给出了另一条路——**不信任供应商，信任可验证的依赖闭包**：lockfile 锁版本、哈希查完整性、可复现构建保证「你跑的就是我审的」、SBOM 记录每个组件从哪来、semver 约束哪些升级可以自动、review/CI 决定什么能合入。把每个模态生成器看成一个 ESM（证据技能模块），「这个模态是真的吗」就变成一个**可检查的问题**：它是否出现在一个锁定、哈希匹配、契约可满足的闭包里？它的来源与当前证据是否同源？这把 R69 的「MCG 一个 ECE 门」升级为**逐模块、逐路径、逐来源的供应链校验**。

**灵感 2（语义化版本 → 不是所有更新都平等）**
直觉：R69 一旦发现模态分布漂移，只能「退回保守」或「整体重训再赌 ECE」；它没有中间态。semver 给出一个精确的中间态：**patch**（只修标定/数值，契约语义不变）与 **minor**（新增能力但向后兼容）可以在通过契约测试后自动升级；**major**（改变契约语义、改变「模态」的含义、触及安全不变量）绝不能在环路内发生，必须走出环的重新验证。这样生态可以演化，但演化的每一步都有可证明的行为变化上界。

**灵感 3（fork / PR / review → 交互本身是供应链动作）**
直觉：R69 的信息动作只有看/问/触。开源实践中，面对不确定还有三种标准动作：**fork**（在沙箱里造一个变体去验证假设，不影响主干）、**pin**（降级回已知良好的版本）、**开 issue / 提 PR**（把问题交给上游，但答案是**补丁提案**，不是圣旨）。把这三者加入动作空间，「问」就不再是「相信一个回答」，而是「提交一条待评审的证据/补丁」；答案可以有信息量，但在被 k 个**来源不相交**的证据复核前，不能改变任何被信任的模块。

**灵感 4（强化学习训练 → 学「组合与选择」，不学「验证」）**
直觉：何时 fork、何时 pin、何时 probe、在几个已验证闭包里选哪个，这些都不该手调，应该从日志里学。但关键设计律是：**验证函数不能进入策略的动作空间**。lockfile 盾在一个 episode 内冻结闭包；RL 只能「在预先验证过的闭包之间选择」，不能构造新闭包、不能改写验证、不能在线合入补丁。这样奖励黑客的攻击面被限制在「选哪个已验证的东西」，而不是「什么算已验证」——后者才是致命的。

**灵感 5（供应链攻击 → R69 的威胁模型有了精确名字）**
直觉：R69 担心「幻觉模态」与「误导回答」，但只把它们当一般噪声。开源软件把它们变成了有标准防法的具体攻击：**typosquatting**（幻影模态冒充真模态）、**dependency confusion**（高版本号的未验证模块抢在真模块前面被解析）、**backdoored patch**（在主分布上通过标定、只在触发分布上改变模态权重的后门更新）、**abandoned dependency / bus factor**（模块陈旧、无人维护，契约悄悄失效）、**correlated provenance lie**（两个「正交」证据其实来自同一份上游数据）。R70 的威胁模型因此可以写成 ℰ_FLUID × ℰ_OSS，每一条都有对应机制，而不是一句「要小心」。

**灵感 6（综合 → R69 是「单模块 + 空补丁队列 + 常数策略」的退化闭包）**
直觉：若生态里只有一个模块、一个锁定版本，无 fork、无 patch、无 RL，那么契约检查是空真、闭包选择是常数、供应链动作集为空——COMMONS-RAS 逐指令等于 FLUID-RAS。因此新层不是并列替代，而是 R69 在「生态退化为单体」边界上的**严格泛化**；安全侧不做任何让步，效率侧获得「可审计的演化能力」。

## 1. 形式化定义（增量：定义 310–326）

**定义 310（COMMONS-RAS 总览）** COMMONS-RAS = (ESM, ECM, EDR, LOCK, PSC, PRC, SCS, DEM, SBOM-E, CRV, RLC, RAS-WM†)。三不变式：
(i) **前台零学习写**（继承 R68 定义 276-i、R69 定义 293-i）；
(ii) **验证闭包不变式**：任何进入 VoI 或交互决策的模态，必须来自一个版本已锁定、哈希已校验、契约可满足的依赖闭包；**无来源（provenance）的模态不得作为证据，也不得进入 VoI**；
(iii) **环路内不合并**：任何新版本、fork 结果或会改变模块行为的回答，只能通过环路之外的 PRC（补丁评审）改变生态；单个 episode 内 lockfile 不可变。

**定义 311（证据技能模块 ESM）** e = (id, ver, φ, κ, μ, τ)。φ: O → 2^ℳ 为模态提议器（可复用 R69 的流匹配速度场）；κ 为认知契约（定义 312）；μ 为清单 manifest = (data_hash, build_hash, calibration, deps, license, owner, freshness)；τ 为测试套件（契约测试 / 标定测试 / 对抗测试 / 差分测试）。ver 为语义化版本 (major.minor.patch)。

**定义 312（认知契约 κ）** κ = (pre, post, inv, fail, dom)。pre 为对输入/观测分布的假设；post 为对输出模态的保证（覆盖率 ≥ α、模态 ECE ≤ ε、可分性 claim、标定记录）；inv 为安全不变量；fail 为声明的失效模式及其严重度；dom 为适用域标签（任务/光照/用户类型/传感器配置）。κ 在状态 s 上**可满足** ⇔ s 的局部证据满足 pre 且 s ∈ dom。组合边 e → e′ 合法 ⇔ e.post ⊆ e′.pre 且 inv 相容。契约是**可测试的过近似**，不是口号。

**定义 313（依赖闭包 C）** C = (V, E, lock)。V ⊆ ESM，E ⊆ 契约相容边，lock = {(id, ver, hash)}。C **有效** ⇔ (a) 依赖全部可解析；(b) 每个哈希与 manifest 一致；(c) 任一路径上的契约链可满足；(d) 不存在两个模块对同一模态身份声明不相容的保证（冲突必须显式报告，不得静默平均）；(e) τ 全通过。Modes(C) 为组合语义下可产生的模态集合。

**定义 314（模态来源账本 SBOM-E）** 对每个模态 m_k 记录：产它的 e@ver、输入 data_hash、build_hash、标定记录、以及把它纳入闭包的证据链。记来源根集合 P(m_k) 为 m_k 依赖的全部上游数据/模型/发布者根；**来源不相交** P(m_i) ∩ P(m_j) = ∅（或重叠度 ≤ ρ_max）。无 SBOM-E 记录的模态，其 U_epi 不可用于交互决策。

**定义 315（认知语义化版本）** major：契约语义、模态含义或安全不变量改变 → **禁止环路内升级**，需出环重新验证；minor：新增能力且契约向后兼容 → 通过 CI 后可在 episode 边界自动升级；patch：仅标定/数值修复 → 通过 CI 后自动升级。对 patch/minor，在契约测试通过时要求模态权重的一阶移动 ≤ δ_semver。

**定义 316（Lockfile 盾）** 每个 episode 使用冻结的 L = {(id, ver, hash)}。策略只能在**预先验证过的闭包集** 𝒞 = {C_1,…,C_n} 中选择与 L 相容者；不得在环路内构造新闭包、解析新依赖或改写 L。任何变更必须走后台 PRC，并在 episode 边界以新锁 + 影子/金丝雀部署。这把 R69 的「零学习写」加强为「零依赖解析」。

**定义 317（供应链动作空间）** 𝒜_info 在 R69 的 {g_gaze, g_probe, g_ask} 之外增加：`fork`（在沙箱中实例化变体以验证假设，对 L 无影响）、`pin`（降级回已知良好版本）、`probe`（向上游/人类提问，即 R69 的 g_ask）。三者与任务动作一样通过 C-RAS-WM 认证与交互预算；`fork` 的输出是**提案**，绝不是环路内替换。

**定义 318（补丁评审与 CI：PRC）** 一个补丁提案 y（人类回答中会改变行为的规则/参数、模块新版本、fork 结果）必须通过：(a) 契约测试；(b) 留出集标定测试；(c) 对抗/投毒套件 ℰ_OSS；(d) 相对当前锁定版本的差分测试；(e) 来源哈希与许可证校验；(f) k 个**来源不相交**的评审者一致。全部通过才产生新版本与新锁候选，并在影子/金丝雀后于 episode 边界部署。普通回答不改变模块，只作为似然证据进入 CRV。

**定义 319（来源不相交的契约验证证据 CRV）** 证据源 r_i、r_j 只有在来源根近似不相交（|P(r_i) ∩ P(r_j)| ≤ ρ_max）时才计为正交；否则其欺骗相关 ρ → 1。定义有效正交数 k_eff = 来源根划分的类数，而不是传感器/模态个数。R69 的「k 个正交源一致」被修正为「k_eff 个来源不相交的证据一致」。

**定义 320（组合/选择约束 MDP）** M_C = (S, A_C, P, R, C, γ)。A_C = (闭包索引 i, 供应链动作 g)，定义在已验证闭包集上。R = r_task + λ_v·VEC − λ_c·cost − λ_s·staleness；约束为 E[risk] ≤ ε_int、E[#interactions] ≤ B、契约覆盖当前状态、环路内无 major 升级。用保守离线 RL + 盾求解。

**定义 321（奖励黑客感知训练 RLC）** 在来源分层（provenance-stratified）日志上用 CQL/IQL 离线学习；认知信度由独立审计侧（不参与 actor 梯度）在来源不相交模块上计算；用留出独立验证器做 proxy-vs-true 审计，要求 |r_proxy − r_true| ≤ ε_r；只在每个来源分层上 LCB(V(π_θ) − V(π_base)) ≥ τ 的区域部署。关键：**验证不在动作空间里**，因此奖励黑客的收益被闭包粒度限制。

**定义 322（开源供应链威胁模型 AIC-OSS）** ℰ_OSS = {typosquat/幻影模态、dependency confusion、backdoored patch、stale/abandoned 依赖、license/consent 违规、correlated provenance lie}；ℰ_COMMONS = ℰ_FLUID × ℰ_OSS。

**定义 323（差分认知监控 DEM）** 影子流上把锁定闭包 C 与可复现参考构建 C_ref 在同一批输入上比较：模态权重 W1 距离、标定残差、来源哈希一致性。用 CUSUM/序贯检验判定 D > τ_DEM。它构成第三条独立通道：R68 看 (r_res)、R69 看 (Δa)、R70 看「供应链分叉」。

**定义 324（新鲜度与 bus-factor 衰减）** 每个模块有新鲜度 f_e ∈ [0,1]，由数据年龄、维护者/来源多样性、测试覆盖率决定。其契约的有效置信乘以 f_e；当 f_e < τ_f，模块进入隔离区：模态仅在重新验证或提高 aleatoric 下界（契约 pre 降级）后可用。这把「依赖被遗弃」从隐性风险变成显式变量。

**定义 325（认证闭包选择 SCS）** C* = argmax_{C ∈ 𝒞_valid(s)} E[V | C, s]，s.t. 契约覆盖 s 且安全约束满足。若**不存在**覆盖 s 的有效闭包（依赖冲突 / 契约不满足），则 U_epi 标记为「不可交互消解」，直接走 R69 保守兜底。系：**不是所有歧义都能问；没有可信模块覆盖时，提问本身不安全**——这是对 R69「总可以问」的正面修正。

**定义 326（COMMONS 证书与严格包含）** J_COMMONS = (J_FLUID, closure_hash, lock_hash, sbom_hash, contract_check, per_module_ECE, provenance_disjointness, prc_hash, rl_audit_margin, dem_flag, semver_compat, license_consent)。Valid ⇔ Valid(J_FLUID) ∧ 闭包有效 ∧ 锁已冻结 ∧ 契约可满足 ∧ 证据来源不相交 ∧ rl_audit_margin ≥ 0 ∧ 无未决 major 升级。退化规则：闭包无效 / DEM 报警 / 审计余量为负 / 有未决 major 时，禁用非 pin 的供应链动作，λ = λ_floor(U_ale + U_epi)（继承 R69 定义 307）。当生态为「单模块 + 空补丁队列 + 常数策略」时，输出与 FLUID 逐指令相同。

```python
# IP-264 ESM：证据技能模块 = 可测试、可溯源、带契约的模态提议器
class EpistemicSkillModule:
    def __init__(self, id, ver, phi, contract, manifest, tests):
        self.id, self.ver, self.phi = id, ver, phi
        self.contract, self.manifest, self.tests = contract, manifest, tests

    def covers(self, s):
        return self.contract.pre(s) and s in self.contract.dom

    def propose(self, o):                       # 可复用 R69 FMP 的 v_θ
        return self.phi(o)                      # -> modes, provenance

# IP-265 ECM + IP-266 EDR：契约匹配与语义化依赖解析（离线 / 边界）
def resolve(root, registry, allowlist):
    # 只接受 allowlist 中的来源根；拒绝同名不同源的 dependency confusion
    deps = registry.dependencies(root)
    if any(d.source_root not in allowlist for d in deps):
        return Conflict("untrusted source")
    # patch/minor 自动；major 只能返回 PENDING_REVIEW，绝不进环路
    picks = [pick_max_compatible(d, semver='patch/minor') for d in deps]
    if any(d.major_upgrade_requested for d in deps):
        return PendingReview(deps)
    return Closure(root, picks, lock=hash_all(picks))

# IP-267 LOCK：环路内只做哈希校验，绝不做解析
class LockfileShield:
    def valid(self, C, L):
        return C.lock == L and all(hash_ok(e) for e in C.V)

# IP-270 SCS：只在已验证闭包中选择；无覆盖 -> 直接 R69 兜底
def select_closure(closures, s, rl_policy, L):
    valid = [C for C in closures if LOCK.valid(C, L) and covers(C, s)]
    if not valid:
        return None                             # 不可交互消解（定义 325）
    return max(valid, key=lambda C: rl_policy.value(C, s))

# IP-272 DEM：差分第二意见（供应链分叉检测）
def differential_monitor(C, C_ref, shadow_stream):
    d = w1(mode_weights(C, shadow_stream),
           mode_weights(C_ref, shadow_stream))
    return cusum(d) > TAU_DEM

# IP-268 PRC：回答/补丁作为提案，出环评审；环路内绝不合并
def review_patch(y, current, tests):
    checks = [contract_test(y, tests),
              calibration_test(y, heldout),
              adversarial_test(y, EPS_OSS),
              differential_test(y, current),
              provenance_check(y),
              reviewer_quorum(y, k_eff=provenance_classes(y), disjoint=True)]
    if all(checks):
        return Merged(version=bump_semver(current, y))
    return Rejected(y)

# IP-273/274 RLC：来源分层上的保守离线 RL；验证不在动作空间
def train_composition(logs, pi_base):
    D = provenance_stratify(logs)               # 每层单独覆盖检查
    pi = cql_iql(D, reward=task + lambda_v * auditor_credit)
    return shield_and_anchor(pi, pi_base, strata=D.strata)  # LCB 门

# IP-277 主闭环：R69 路径 + 闭包选择 + 供应链动作 + 三通道第二意见
def COMMONS_RAS_round(M, obs):
    z, o = M.mtm.forward(obs)
    c, U_cal, thr = M.cof.step(...)             # R68 标定
    # 1) 环路内只读锁：选一个已验证闭包，绝不解析新依赖
    C = M.scs.select(M.closures, state, M.rlc.policy, M.lock)
    if C is None:                               # 契约不覆盖 -> 不可问
        U_ale, U_epi = M.aud.decompose(M.fmp.sample(o, 1), z, M.mode_head)
        lam = lam_floor(U_ale + U_epi)
        return M.r69_fallback(lam, ...)
    # 2) 闭包内多模块提议模态，带 SBOM-E 来源
    modes = M.esm_bank.propose(C, o)
    U_ale, U_epi = M.aud.decompose(modes, z, M.mode_head)
    # 3) 三条独立第二意见：残差 / 行为似然 / 供应链分叉
    a_hat = M.fma.flow_anomaly(M.fmp, M.last_action, obs, o_calibrated)
    dem   = M.dem.check(C, o)
    slow  = (a_hat > TAU_FMA) and (M.last_r_res < TAU_RES)
    # 4) 供应链动作（probe/fork/pin）由 RL 提议，盾与预算裁决
    g = None
    if U_epi > TAU_EPI and not slow and not dem:
        g = M.psc.choose(modes, o, M.budget, M.rlc.policy, C,
                         allow={'probe', 'fork', 'pin'})
    if g is not None and g.kind == 'probe':
        y = M.psc.execute(g)                    # 回答只是似然证据
        U_epi = M.crv.update_belief(modes, y, discipline='k_eff_disjoint')
    if g is not None and g.kind in ('fork', 'pin'):
        M.prc.submit_async(g)                   # 补丁提案，出环评审
    # 5) 风险缩放：未消解/被污染则回 R69 兜底
    U_floor = U_ale + (U_epi if g is None else 0.0)
    lam = max(M.efs.risk_scale(...), lam_floor(U_floor))
    if slow or dem:
        lam = max(lam, 0.8)
    mode = select_mode(modes, U_epi, lam)
    k = M.c_ras_wm.certified_prefix(M.ach.propose(...), ..., M.wm_preds)
    tau = M.pi_sigma.prefix_dispatch(mode.a[:k]) * lam
    # 6) 参与式审计 + 供应链证书
    M.vqa_oss.submit_async(C, g, U_epi, a_hat, dem)
    return k, lam, mode, (U_ale, U_epi), J_COMMONS(C)
```

## 3. 推导

**假设增量** A99（来源可识别且哈希稳定：每个模块/数据的来源根可判定、构建可复现）；A100（契约是保守过近似：post 不弱于真实行为，可被测试集证伪）；A101（差分流的触发分布覆盖率 ≥ q_min，影子流非空）；A102（闭包图无环且深度 ≤ d_max）；A103（离线日志按来源分层后每层满足倾向覆盖 e_min，且行为策略包含 π_base）；A104（R68/R69 的认证前缀与风险界成立）。

**引理 19（来源不相交的证据上界）** 设单源欺骗率 δ_p，来源根相关 ρ ∈ [0,1]；k 个证据源多数一致时，错误采纳率 ≤ δ_p·ρ^{k_eff−1} + ε_σ，其中 k_eff 为来源根划分的类数。若两个「正交模态」共享同一上游数据/模型，则 ρ → 1，无论传感器多少个，k_eff = 1，上界退化为 δ_p。系：**R69 的 k-正交纪律可被同源共谋骗过；「正交」必须按来源定义，而不是按模态名定义**。

**引理 20（无闭包覆盖时交互的劣势）** 若不存在覆盖 s 的有效闭包，则任何交互要么使用无 SBOM-E 来源的模态（风险不可界），要么违反某个已声明契约（inv 或 pre）。在 A99–A100 下，其期望风险 ≥ ε_int；而 R69 保守动作的风险 ≤ ε_int。故 SCS 返回 None 时保守兜底是占优策略。系：**歧义并非总能通过提问消解；没有可信模块覆盖时，「问」比「不问」更危险**。

**引理 21（语义化升级的行为上界）** patch/minor 若通过契约、标定、对抗、差分四类测试，则其模态权重的 1-Wasserstein 移动 ≤ δ_semver，且 VoI 变化 ≤ L_V·δ_semver（L_V 为 VoI 对模态权重的 Lipschitz 常数）。major 改变契约语义，无此上界，故只能在出环重新验证后于 episode 边界引入。系：**生态可以自动演化的是「标定」与「兼容能力」，不能自动演化的是「模态意味着什么」**。

**引理 22（后门补丁的可检测性）** 设后门在触发分布 T 上把模态权重改变 Δ，T 在影子流中占比 ≥ q。则 n 个影子样本中至少命中一次触发的概率 ≥ 1−(1−q)^n；DEM 的 W1 统计量在命中时期望 ≥ Δ，故在 CUSUM 下检测功效随 Δ√n 增长。R69 的单次 ECE 门只在主分布上测量，对这类触发式后门**结构性失明**。系：**可复现构建 + 差分监控，是 R69 最大风险（模态分布不可信）的直接补丁**——它把「相信」替换为「复现并比较」。

**引理 23（奖励黑客被闭包粒度限制）** 在 lockfile 盾下，策略动作空间不含「改变验证」的操作，所有可选闭包均已预先验证。故对任意策略 π，可达信念状态限于 𝒞 中的闭包；代理-真实奖励差 ≤ ε_r + Δ_C，其中 Δ_C = max_{C,C′∈𝒞} |V(C)−V(C′)|。系：**降低可攻击性应通过细化验证（减小 Δ_C）而非缩小模型容量；验证本身必须被移出策略的优化对象**。

**定理 18（COMMONS 严格包含 FLUID）** 在 A99–A104 下，对任意状态 s：(i) 安全性：所有模态来自有效闭包，交互经 R69 认证与链路预算，物理风险 ≤ ε_int，证据纪律成立，安全侧不弱于 R69；(ii) 兜底一致性：当闭包无效、无覆盖、DEM 报警、审计余量为负或存在未决 major 时，COMMONS 禁用非 pin 供应链动作并强制 λ = λ_floor(U_ale + U_epi)，与 R69 定义 307 逐指令相同；(iii) 退化：当生态是单模块锁定、补丁队列为空、策略为常数时，契约检查空真、SCS 为恒等选择，输出与 FLUID 完全相同。故 R69 是 COMMONS 在「单体生态」边界上的严格退化。

**定理 19（供应链损坏的传播上界）** 设被污染模块在闭包图中的可达决策比例为 reach(e)，来源不相交冗余的有效类数为 k_eff。则被污染模块导致的决策错误率 ≤ reach(e)·(δ_p·ρ^{k_eff−1} + (1−coverage_T)·Δ_T) + ε_σ，其中 coverage_T 为影子流对触发分布的覆盖。故信任不是全局布尔量，而是**逐模块、逐路径、逐来源**的有界量；增加来源不相交的冗余、提高触发覆盖、缩短依赖深度都能单调降低上界。系：**开源式模块化不是为复用，而是为把「一个模型撒谎」的后果限制在可达子图内**。

**命题 20（可复现 ⇒ 可审计）** 若构建可复现（相同源得到逐位相同的 build_hash），则任何进入决策的模态都能被独立审计方从源重新导出；「已验证」因此可以被定义为「已复现」，而不是「相信供应商」。这使 J_COMMONS 可由第三方离线复核，而不依赖运行时自证。系：**证书的可信度来自可复现性，而不是来自签发者**。

## 6. 本轮最大风险

**一句话**：COMMONS-RAS 的全部信任都押在「契约是诚实的过近似、来源清单不可伪造」上——若某个被污染的模块自报一份干净的 SBOM、或契约本身写错了假设，系统会把一个**投毒的闭包认证成可信**；这比 R69 的 ECE 门更危险，因为 R69 至少只是「诚实地不确定」，而 R70 会用一条完整的审计链为一棵被污染的依赖树**洗白**——**被验证过的错误，比未被验证的无知更难纠正**。

**次级风险与缓解**：契约本身不可靠（契约测试 + 影子差分 + 出环复审，但仍不能证明契约完备）；来源自报/哈希伪造（可复现构建 + 第三方复现 + 签名根，属工程信任根问题）；生态碎片化导致交互被大面积禁用而静默退回 R69（E301/E303 覆盖门 + 退化告警）；RL 在闭包间选择仍可奖励黑客（审计侧信度 + 来源分层 LCB + 减小 Δ_C）；实时预算被哈希/DEM 击穿（缓存 + 按需触发 + 影子流离线）；人类补丁评审的社交工程（k_eff 不相交评审 + 拒绝单源合入 + E314）。

## 2. 形式化定义（要点版）

**定义 310（总览与三不变式）** COMMONS-RAS 由 12 个组件构成；**前台零学习写**（继承 R68/R69）、**验证闭包不变式**（无来源模态不得进 VoI/证据）、**环路内不合并**（新版本/fork/行为性回答只能出环 PRC，episode 内锁冻结）。

**定义 317–318（供应链动作与 PRC）** `probe`（问）/`fork`（沙箱验证）/`pin`（降级）；fork 输出为提案。PRC 六门：契约、标定、对抗投毒、差分、来源/许可、`k_eff` 来源不相交评审；全过才产生新版本/新锁候选，影子/金丝雀后于边界部署。

**定义 319（CRV）** 有效正交数 `k_eff` = 来源根类数；R69 的「k 个正交源」修正为「k_eff 个来源不相交证据」。同源共谋令 `ρ→1`，传感器再多也无效。

**定义 320–321（组合 CMDP 与 RLC）** 动作是（闭包索引，供应链动作）；奖励含任务 + 审计侧信度 − 成本 − 陈旧惩罚。来源分层 CQL/IQL + proxy-vs-true 审计 + 逐层 LCB；**验证不在动作空间**，奖励黑客收益受 `Δ_C` 限制。

**定义 322–324（威胁/DEM/新鲜度）** `ℰ_OSS` = 幻影、抢注、后门补丁、陈旧依赖、许可违规、同源共谋。DEM 在影子流比较锁定闭包与可复现参考构建（W1/标定/CUSUM），是继 R68 残差、R69 行为似然之后的第三条通道。新鲜度 `f_e` 给契约置信打折，`f_e<τ_f` 进隔离区。

**定义 325–326（SCS 与证书）** SCS 只在覆盖 s 的有效闭包中按价值选择；无覆盖 ⇒ U_epi「不可交互消解」⇒ R69 兜底（**不是所有歧义都能问**）。`J_COMMONS` 并入闭包/锁/SBOM/契约/ECE/来源不相交/PRC/审计余量/DEM/semver/许可；退化时禁用非 pin 动作并 `λ=λ_floor(U_ale+U_epi)`；单体生态 ⇒ 逐指令等于 FLUID。

## 3. 关键算法伪代码

```python
# IP-264/265/266：模块、契约匹配、语义化依赖解析（离线/边界）
def resolve(root, registry, allowlist):
    deps = registry.dependencies(root)
    if any(d.source_root not in allowlist for d in deps):
        return Conflict("untrusted source")          # 拒绝抢注/未验证来源
    picks = [pick_compatible(d, allow=('patch', 'minor')) for d in deps]
    if any(d.wants_major for d in deps):
        return PendingReview(deps)                    # major 绝不进环路
    return Closure(root, picks, lock=hash_all(picks))

# IP-267 LOCK + IP-270 SCS：环路内只读锁，只在已验证闭包中选择
def select_closure(closures, s, policy, L):
    valid = [C for C in closures if lock_valid(C, L) and covers(C, s)]
    return max(valid, key=lambda C: policy.value(C, s)) if valid else None

# IP-272 DEM：可复现参考构建上的差分第二意见
def differential_monitor(C, C_ref, shadow):
    d = w1(mode_weights(C, shadow), mode_weights(C_ref, shadow))
    return cusum(d) > TAU_DEM                       # 触发式后门/供应链分叉

# IP-268 PRC：任何行为性回答/新版本都只是提案，出环评审
def review_patch(y, current):
    ok = all([contract_test(y), calibration_test(y, heldout),
              adversarial_test(y, EPS_OSS), differential_test(y, current),
              provenance_check(y),
              reviewer_quorum(y, k_eff=provenance_classes(y), disjoint=True)])
    return Merged(bump_semver(current, y)) if ok else Rejected(y)

# IP-273/274 RLC：来源分层离线 RL；验证不在动作空间
def train_composition(logs, pi_base):
    D = provenance_stratify(logs)
    pi = cql_iql(D, reward=task + lambda_v * auditor_credit)
    return shield_and_anchor(pi, pi_base, strata=D.strata)   # 逐层 LCB 门

# IP-277 主闭环（继承 R69，仅在「模态从哪来/能否升级」处插入供应链层）
def COMMONS_RAS_round(M, obs):
    z, o = M.mtm.forward(obs); c, U_cal, thr = M.cof.step(...)
    C = M.scs.select(M.closures, state, M.rlc.policy, M.lock)
    if C is None:                                   # 没有可信闭包覆盖 ⇒ 不问
        U_ale, U_epi = M.aud.decompose(M.fmp.sample(o, 1), z, M.mode_head)
        return M.r69_fallback(lam_floor(U_ale + U_epi), ...)
    modes = M.esm_bank.propose(C, o)                # 带 SBOM-E 来源
    U_ale, U_epi = M.aud.decompose(modes, z, M.mode_head)
    a_hat = M.fma.flow_anomaly(M.fmp, M.last_action, obs, o_calibrated)
    dem   = M.dem.check(C, o)
    slow  = (a_hat > TAU_FMA) and (M.last_r_res < TAU_RES)
    g = (M.psc.choose(modes, o, M.budget, M.rlc.policy, C,
                      allow={'probe', 'fork', 'pin'})
         if (U_epi > TAU_EPI and not slow and not dem) else None)
    if g and g.kind == 'probe':
        U_epi = M.crv.update_belief(modes, M.psc.execute(g),
                                    discipline='k_eff_disjoint')
    if g and g.kind in ('fork', 'pin'):
        M.prc.submit_async(g)                       # 提案出环，不即时合并
    lam = max(M.efs.risk_scale(...),
              lam_floor(U_ale + (U_epi if g is None else 0.0)))
    if slow or dem: lam = max(lam, 0.8)             # 回 R69 最保守
    mode = select_mode(modes, U_epi, lam)
    k = M.c_ras_wm.certified_prefix(M.ach.propose(...), ..., M.wm_preds)
    tau = M.pi_sigma.prefix_dispatch(mode.a[:k]) * lam
    M.vqa_oss.submit_async(C, g, U_epi, a_hat, dem)
    return k, lam, mode, (U_ale, U_epi), J_COMMONS(C)
```

## 4. 推导

**假设增量** A99 来源可识别且哈希稳定、构建可复现；A100 契约是保守过近似且可被测试证伪；A101 影子流对触发分布覆盖 ≥ q_min；A102 闭包图无环、深度 ≤ d_max；A103 来源分层后离线日志满足倾向覆盖且含 π_base；A104 R68/R69 认证前缀与风险界成立。

**引理 19（来源不相交证据上界）** 错误采纳率 ≤ `δ_p·ρ^{k_eff−1}+ε_σ`，`k_eff` 为来源根类数。同源共谋令 `ρ→1`，模态再多也退化到 `δ_p`。系：**R69 的 k-正交纪律可被同源数据/模型共谋骗过；正交必须按来源定义**。

**引理 20（无闭包覆盖时交互劣势）** 若无有效闭包覆盖 s，任何交互要么用无来源模态（风险不可界），要么违反已声明契约；期望风险 ≥ ε_int，而 R69 保守 ≤ ε_int，故兜底占优。系：**不是所有歧义都能问；没有可信模块覆盖时，问比不问更危险**——正面修正 R69 的「总可以问」。

**引理 21（语义化升级行为上界）** patch/minor 过四类测试后，模态权重移动 ≤ δ_semver，VoI 变化 ≤ `L_V·δ_semver`；major 无此界，只能出环重新验证。系：**能自动演化的是标定与兼容能力，不能自动演化的是「模态意味着什么」**。

**引理 22（后门补丁可检测性）** 触发分布占比 ≥ q，n 个影子样本至少命中一次的概率 ≥ `1−(1−q)^n`；DEM 的 W1 在命中时 ≥ Δ，CUSUM 功效随 `Δ√n` 增长。R69 的单次 ECE 门只在主分布测量，对触发式后门结构性失明。系：**可复现构建 + 差分监控，是 R69 最大风险（模态不可信）的直接补丁——把「相信」换成「复现并比较」**。

**引理 23（奖励黑客受闭包粒度限制）** 锁盾把「改变验证」移出动作空间；可达信念限于预验证闭包，代理-真实奖励差 ≤ `ε_r+Δ_C`。系：**降低可攻击性靠细化验证（减小 Δ_C），不是缩小模型容量；验证本身不能被优化**。

**定理 18（COMMONS 严格包含 FLUID）** A99–A104 下：(i) 所有模态来自有效闭包，交互过 R69 认证与预算，安全侧不弱；(ii) 闭包无效/无覆盖/DEM 报警/审计余量为负/未决 major 时，禁用非 pin 动作并 `λ=λ_floor(U_ale+U_epi)`，与 R69 定义 307 逐指令相同；(iii) 单体锁定 + 空补丁 + 常数策略 ⇒ 输出与 FLUID 完全相同。R69 是「单体生态」边界上的严格退化。

**定理 19（供应链损坏传播上界）** 污染模块影响 ≤ `reach(e)·(δ_p·ρ^{k_eff−1}+(1−coverage_T)·Δ_T)+ε_σ`。信任是**逐模块、逐路径、逐来源**的有界量；来源不相交冗余、提高触发覆盖、缩短依赖深度都单调降低上界。系：**开源式模块化不是为了复用，而是把「一个模型撒谎」的后果限制在可达子图内**。

**命题 20（可复现 ⇒ 可审计）** 构建逐位可复现时，任何进入决策的模态都能被独立审计方从源重新导出；「已验证」=「已复现」，不依赖运行时自证或签发者。系：**证书可信度来自可复现性，而非权力**。

## 7. 本轮最大风险

**一句话**：COMMONS-RAS 的全部信任都押在「契约是诚实的过近似、来源清单不可伪造」上——若被污染模块自报干净 SBOM，或契约写错了假设，系统会把一棵**投毒的依赖树认证成可信**；这比 R69 的 ECE 门更危险，因为 R69 只是「诚实地不确定」，而 R70 会用完整审计链为污染**洗白**——**被验证过的错误，比未被验证的无知更难纠正**。

**次级风险与缓解**：契约不可靠（契约测试 + 影子差分 + 出环复审，但无法证明契约完备）；来源自报/哈希伪造（可复现构建 + 第三方复现 + 签名根，属工程信任根）；生态碎片化使交互被大面积禁用而静默退回 R69（E301/E303 覆盖门 + 退化告警）；RL 在闭包间选择仍可奖励黑客（审计侧信度 + 来源分层 LCB + 减小 Δ_C）；实时预算被哈希/DEM 击穿（缓存 + 按需触发 + 影子流离线）；人类补丁评审社交工程（k_eff 不相交评审 + 拒绝单源合入 + E314）。
