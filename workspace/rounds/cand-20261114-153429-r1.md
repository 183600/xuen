# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配交互消歧闭环」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「论文发表」×「技术融合」）

> R69 教会系统「向谁求证」，却对两件事过于天真：
> - **证书是自签的**：J_FLUID 由系统自己计算、自己判定 Valid，像一篇没有预注册、没有同行评审、没有撤稿机制的预印本。系统越会问、越会生成，就越容易「自信地错着」，并把这种自信写进证书；
> - **技术是拼起来的**：FMP、AUD、MINT、CIA、FMA、校准器、冻结 LLM、控制器是**异质模块的融合**。每个模块在自己的测试集上 Valid，却在接口处产生任何单模块都测不到的涌现风险（问句→人类→策略→标定→下一问的闭环、交互诱发的标定漂移、LLM 与流策略共谋出的自洽错误）。
>
> 本轮两个灵感恰好各补一刀：
> - **论文发表**提供一套成熟的认识论协议：**预注册锁定范围 → 可复现证据 → 独立同行评审 → 声明依赖与引用 → 撤稿/勘误**。它把「我说我安全」变成「一个持怀疑态度的外部者能独立复核、并在我越界时撤销我的声明」。格言：**审稿通过 ≠ 为真；可复现 ≠ 正确；接收率不是目标，校准才是。**
> - **技术融合**提供一套组合语义：融合不是模块相加，而是在**接口**上生成新对象；组件契约（assumption / guarantee / scope / error）不可直接提升为系统契约，必须逐边提供**接口见证**，并为**涌现属性**单独设计联合探针。
>
> 核心命题：**把每条安全/能力断言升格为「可发表、可复现、可被独立审稿、可被单调撤稿、且只在声明范围内有效」的声明对象；把多技术栈看作带契约的融合 DAG，系统级声明必须逐接口见证并显式计入涌现项。** 命名 **PEER-RAS**（Pre-registered, Evidence-scoped, Emergent-interface, Retractable Risk-Adaptive System）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**我凭什么让一个不信任我的外部者相信这份安全声明？当技术被融合之后，这份声明还在它的适用范围里吗？**」——证书不是奖状，是一篇可以被拒稿、被复现失败、被撤稿的论文。

## 0. 直觉与动机

**灵感 1（论文发表 = 认识论协议，而不是写作技巧）**
直觉：一篇论文之所以可信，不因为它排版漂亮，而因为它做了五件事：**把断言写在明处（φ）、把适用范围写清楚（S）、在收集证据前先注册检验（预注册）、让独立的人用独立数据复核（同行评审/复现）、在证据推翻它时公开撤回（撤稿）**。把这五件事搬到机器安全上，正好补上 R66–R69 一路自签证书的死穴：前面每一层都默认「验证者与被验证者同源」，而论文协议第一次强制**验证者独立**。

**灵感 2（技术融合 = 接口上的新物种）**
直觉：把相机、LLM、流策略、控制器接在一起，不是「1+1=2」。每个模块的保证都是**有条件的**（在它的假设 A_i、范围 S_i 内）；融合后 j 消费 i 的输出，若 i 的保证不满足 j 的假设（单位、坐标系、时延、置信语义、分布支撑），就出现**接口残差 δ_ij**。更麻烦的是，有些性质只在联合闭环里出现——「问完会不会诱发标定漂移」「LLM 的追问会不会与流策略的模态坍缩共振」——任何单模块测试集都测不到。**融合的风险不可加，也不可忽略。**

**灵感 3（把两者接起来：融合声明就是一篇论文）**
直觉：当系统说「这套融合栈在 S 内风险 ≤ ε」，这就是一个**声明**，它具备一篇论文的全部结构：论点（φ）、适用范围（S）、假设（各模块契约 A）、实验（接口见证与涌现探针 E）、审稿人（独立证据源 R）、以及撤稿条件（漂移/越界/反例）。所以「论文发表」不是隐喻——它是融合系统唯一诚实的证书格式：**没有 scope 的证书就是没有限制条件的定理，既不可证伪也不可信任。**

**灵感 4（预注册 = 对抗运行时偷看）**
直觉：运行时系统持续监控证据，如果「看到显著就宣布安全、看到不显著就继续测」，这正是统计上的 p-hacking。论文界用**预注册 + 序贯检验（anytime-valid e-process）**解决：检验协议在看数据前锁定，置信序列在任意停止时刻都保持有效。搬到运行时，就是**范围与接受规则预注册、监控用 e-process**——既不因持续偷看而虚高撤稿率，也不允许事后扩大 scope 把失败解释成成功。

**灵感 5（撤稿单调 = 安全侧的不可逆性）**
直觉：科学上撤稿可以「平反」，但安全上不行：一个已被证伪的安全声明若能在没有**全新独立证据**时悄悄复活，就形成「僵尸证书」。所以铁律是**单调撤稿**：失效沿声明依赖图向后裔传播，恢复必须换新 id、重新预注册、重新独立审稿；恢复后的风险下限带滞回，不能「一恢复就放松」。

**灵感 6（元审稿 = 审稿人也会错，也会被收买）**
直觉：R69 最大风险是「问错比不问更危险」；本轮风险升级为「**审稿错了比不审更危险**」：一个被投毒或校准不良的 reviewer 会把错误声明盖章为 accepted。所以必须**审稿审稿人**：用未参与该声明的第三方证据估计 reviewer 错误率 γ 与审稿间相关 ρ_R；并明确反对 Goodhart——激励目标是「对照复现的校准误差」，不是「接收率」。

**灵感 7（严格包含 R68/R69）**
直觉：把融合图退化成单模块（无边、δ=0、ε_emerge=0）、把审稿退化为「证据源不相交的自审」、并关闭一切撤稿触发时，PEER 逐指令退化为 FLUID；再令 VoI≤成本即退化为 R68。多出来的预注册、见证、撤稿只会**更保守**，不会更激进。

## 1. 形式化定义（增量：定义 310–327）

**定义 310（PEER-RAS 总览）** PEER-RAS = (CLM, PREREG, REPRO, REV, CDAG, FUSE, IW, EP, CCA, META, RAS-WM†)。六不变式：
(i) **实时流零学习写操作**（继承 R69 定义 293-i；预注册/复现/审稿只在维护窗口离线运行）；
(ii) **无范围不声明**：任何被执行的声明必须携带 scope S 与证据 E，禁止全局/无界声明；
(iii) **预注册锁定**：φ、S、检验协议与停止规则在证据生成前冻结，事后扩界 = 新声明；
(iv) **审稿独立**：reviewer 证据源与 claimant 证据源不相交（互信息泄漏 ≤ ρ0）；
(v) **撤稿单调**：一旦 retracted，所有后裔同步失效；同 id 不得复活，重新生效必须新 id + 新预注册 + 新独立证据；
(vi) **融合局部性**：系统级声明必须对每条融合边提供接口见证，组件声明不可直接提升为系统声明。

**定义 311（声明对象）** C = (id, φ, S, A, E, R, τ, h, status)。φ 为断言（如「在 S 内风险 ≤ ε」）；S ⊆ 状态-动作-环境空间（operating envelope）；A 为依赖的模块契约假设；E 为证据包；R 为审稿证据集；τ 为有效期；h = hash(E, A, S, 协议版本)；status ∈ {draft, registered, under_review, accepted, retracted, superseded}。

**定义 312（预注册与范围锁 PREREG）** 在采集 E 之前提交 P = (φ, S, 检验统计量, α, 停止规则, 版本) 到不可篡改日志。运行期若 x_t ∉ S，声明不被外推，而触发 scope violation（定义 325），且扩界必须新 id。

**定义 313（可复现摘要 REPRO）** Rep(C) = H(replay(E; seeds, env_manifest, code_hash))。accepted 要求两次**独立运行时**（主系统 + 数字孪生/影子模式）Rep 一致；不一致 → 退回 under_review。**Rep 只证明「可重复」，不证明「为真」**——这是必须写进证书的认识论边界。

**定义 314（anytime-valid 审稿检验）** 审稿检验由 e-process {E_n} 给出：E_0 ≤ 1，对任意停时 τ 有 E[E_τ | φ 真] ≤ 1；当 E_n ≥ 1/α 拒绝 φ。检验力 β(C) = P[E_τ ≥ 1/α | φ 假]，要求 β ≥ β_min。**好处**：运行期可以每步偷看而不付出多重检验代价，错误接受/错误撤稿率仍 ≤ α，把「预注册」与「实时监控」统一。无法定义 T（不可证伪）的声明一律拒稿。

**定义 315（审稿独立性 REV）** 令 V_C、V_R 为 claimant 与 reviewer 的证据源集合。独立性分数 ι(C) = 1 − I(V_C; V_R)/H(V_C)。要求 ι ≥ ι0。R69 的「k 源一致」若 k 个源共享同一上游，则不满足本定义，不能计入 k。

**定义 316（声明依赖图 CDAG）** 有向无环图 G_C = (𝒞, →)；C_i → C_j 表示 C_j 的证明引用了 C_i。提供 provenance 与影响传播路径；检测到环 = 自证，直接拒稿。

**定义 317（撤稿传播）** retract(C) 使 status(C) = retracted，且 ∀C' ∈ Desc(C)，status(C') = retracted；传播 O(|𝒞|+|E|)。**僵尸防护**：retracted 节点的证据在未获新独立证据前不得再次作为支持；重新接受必须新 id，禁止「翻案」。传播是保守的：可能过度撤稿，但绝不漏撤。

**定义 318（技术融合算子 FUSE）** 模块 M_i 通过 ⊗ 组合：串行 ∘、并行 ⊕、反馈 ↺。融合系统 M_⊗ 的状态空间为接口变量与内部变量之并；耦合由接口变量 I_ij 建立。

**定义 319（模块契约）** K_i = (A_i, G_i, S_i, ε_i)：在假设 A_i 与范围 S_i 内，M_i 保证 G_i 且误差 ≤ ε_i。契约是**条件保证**，不是无条件保证。

**定义 320（契约兼容与接口残差 IW-1）** 对边 i→j（j 消费 i 的输出），要求 A_j 在 G_i 下成立。接口残差 δ_ij = d_I(G_i|_I, A_j|_I)，在接口变量 I_ij 上度量（单位、坐标系、时延、量纲、置信语义）。δ_ij > 0 即契约不兼容：融合前必须有适配器或见证补偿。

**定义 321（接口见证 IW-2）** W_ij 为在**融合后联合分布**上检验 A_j 的测试集及覆盖率 cov(W_ij)。在单模块测试集上验证 A_j 不算——它不在融合上下文里。融合声明 Valid 要求 ∀ 边 cov(W_ij) ≥ cov_min。

**定义 322（融合风险上界）** 在 ∧_i A_i 下，
Risk(M_⊗) ≤ Σ_i w_i ε_i + Σ_{i→j} λ_ij δ_ij + ε_emerge + ε_int，
其中 w_i、λ_ij 为可在线估计的灵敏度（Lipschitz 常数），ε_emerge 仅由定义 323 的探针估计。系：**即使每个 ε_i = 0，δ_ij > 0 或 ε_emerge > 0 仍可能使系统不安全**——有效组件的融合未必有效。

**定义 323（涌现属性探针 EP）** 对不属任何单模块的联合属性 ψ（如「问后动作闭环稳定」「交互不诱发标定漂移」），E_emerge 从接口联合分布 p(I_12, …) 采样，且必须包含**跨模块时序对**（ask → human reply → policy → calibration → next ask）。涌现声明只能由 E_emerge 支持，组件证据不可替代。

**定义 324（声明携带动作 CCA）** 每个动作块 ξ_{t:t+H} 附带其依赖的最小声明集 id(C_used)。运行时监视器检查 accepted ∧ x_t ∈ S ∧ 未过期；否则动作降级为 R68 λ_floor 保守策略。这是把 certificate-carrying code 从静态推广到**行为**。

**定义 325（撤稿触发与单调退避）** 触发集合：scope violation、R68 漂移、R69 FMA 异常、OOD、审稿反例、接口见证失效、过期。任一触发 → 撤稿并 λ ← max(λ, λ_floor(U_ale + U_epi))，与 R68/R69 兜底一致；退避单调，恢复需重新审稿且 λ 带滞回，不得因恢复而低于当前保守下限。

**定义 326（J_PEER 证书）** J_PEER = (J_FLUID, claim_id, scope_hash, rep_digest, pre_reg_hash, β, ι, witness_cov, retraction_state, peer_ver)。Valid ⇔ Valid(J_FLUID) ∧ status = accepted ∧ Rep 一致 ∧ β ≥ β_min ∧ ι ≥ ι0 ∧ witness_cov ≥ cov_min ∧ 声明未撤稿。

**定义 327（元审稿 META 与反 Goodhart）** Reviewer 错误率 γ、审稿间相关 ρ_R 用**未参与该声明**的第三方探针估计，要求 γ ≤ γ_max、ρ_R ≤ ρ_max。激励目标为「对照复现的校准误差」而非接收率；否则系统会学会写讨审稿人喜欢的论文，而不是安全的系统（Goodhart）。

# IP-268 CDAG：依赖图与单调撤稿传播
def retract(C, reason):
    q = deque([C])
    while q:
        c = q.popleft()
        if c.status != "retracted":
            c.status, c.retract_reason = "retracted", reason
            q.extend(c.children)                 # 所有后裔同步失效（僵尸免疫）
    return reason

# IP-269/270 FUSE + IW：契约融合与接口见证
def fuse(modules, dag):
    for (i, j) in dag.edges:
        delta = interface_residual(modules[i].contract.G,
                                   modules[j].contract.A,
                                   on=interface_vars(i, j))     # 定义 320
        cov   = witness_coverage(fused, i, j)                   # 必须在融合后联合分布上测
        if delta > DELTA_MAX or cov < COV_MIN:
            fused.requires_adapter(i, j, delta)                 # 或拒绝融合
    return fused

def claim_carrying_step(M, obs):

def meta_review(reviewers, third_party_probe):

## 3. 推导

**引理 19（融合不可加性 / no free composition）** 存在模块 M_1、M_2 满足各自契约（ε_1 = ε_2 = 0，在 S_1、S_2 内），但其融合 M_1∘M_2 的接口残差 δ_12 > 0，使 Risk(M_⊗) ≥ λ_12·δ_12 > 0。构造：M_1 输出以「毫秒」为时延语义，M_2 假设「秒」；两者本地测试集均零误差，串联后时延错 1000×。故 {Valid(K_i)} 不能推出 Valid(K_⊗)。系：把「模块都过了」当成「系统过了」是一种**合成谬误**；系统级声明必须逐边见证。

**引理 20（审稿独立性与投毒放大）** 设攻击者对某证据源的污染成功率为 δ_p，reviewer 与 claimant 证据源重叠比例为 1−ι。若重叠源被污染，即使 reviewer 其他源干净，错误接受率满足 Err ≥ (1−ι)·δ_p·χ（χ 为重叠证据对该声明的支持权重）；当 ι → 1，Err ≤ ε_σ。系：**独立审稿不是流程正确，而是数量级上的安全性**；共享上游的「多源」不算多源。

**引理 21（撤稿传播的可靠、保守与僵尸免疫）** 对声明 DAG G_C，撤稿传播 O(V+E)。设真受影响集合 A* 为证明传递依赖失效声明者，传播后失效集合 Ret ⊇ A*（可靠/保守）；若重新接受要求新 id 与新预注册，则不存在同 id 复活的僵尸声明。证明：传递闭包包含所有后代；单调性来自状态转移只允许 retracted→retracted（同 id）。

**定理 18（PEER 严格包含 FLUID）** 在 A99–A102（融合图单节点、δ = 0、ε_emerge = 0、ι = 1、β ≥ β_min、无撤稿触发）下，PEER 与 FLUID 在任意状态逐指令相同；一般情形下 PEER 的执行风险 ≤ FLUID 的执行风险 + ε_review（独立审稿的误接受界），且任何 scope violation/撤稿触发都切到与 FLUID/R68 相同的 λ_floor 兜底。因此 PEER 是 FLUID 在「单模块 + 完美独立自审 + 无漂移」边界上的退化，安全侧不让步。

**定理 19（融合安全上界与无突变）** 若定义 321 所有接口见证 cov ≥ cov_min、定义 323 涌现探针通过（e-process 未拒绝）、且定义 322 上界 ≤ ε，则融合系统在 S_⊗ 内执行风险 ≤ ε + ε_review + ε_scope；任一撤稿触发使 λ 单调不降并切到 R68 认证前缀，换装不变式（R68 定理 15）保持 ⇒ 控制连续、无突变。

**定理 20（anytime-valid 与反 Goodhart 的激励相容）** (i) 若接受规则是定义 314 的 e-process，则对任意自适应采样/停止策略，错误接受率 ≤ α，且不随运行时长增长；(ii) 在 A103（reviewer 收益 = 负校准误差，校准用未参与声明的第三方探针）下，任何「缩小 scope 以更容易通过」的策略不增加收益，Goodhart 通道被切断。故持续监控与自适应采样都不抬高错误接受率。

## 6. 本轮最大风险

**一句话**：PEER-RAS 把「系统说自己安全」升级为「一个审稿系统说它安全」，但如果审稿分布、接口见证与涌现探针都由同一套基础设施生成，整个声明 DAG 就会共享同一个**未被验证的接口/审稿盲区**——**技术融合把一张张『已接收』的论文叠成一座纸牌屋，而审稿通过只是让它看起来更像真的；最危险的不是没有证书，而是一叠互相引用、共同错误的证书。**

**次级风险与缓解**：
1. **审稿 theater / Goodhart**（系统学会讨好审稿而非变安全）→ 元审稿 + e-process + 校准型激励 + E312；
2. **接口见证成本爆炸**（边数平方）→ 只在变更/高风险边强制见证 + 影响分析剪枝 + E303；
3. **撤稿抖动与过度保守** → 分级撤稿（soft/hard）+ 滞回 + E314；
4. **预注册僵化难以适应真实漂移** → 版本化预注册（新 id），禁止原地扩界；
5. **声明 DAG 循环自证** → 拓扑检查 + 禁止自引用 + 独立源约束；
6. **复现只证可重复、不证正确** → 明确认识论边界，用第三方涌现探针补证，绝不把 Rep 当 truth。

class ClaimLedger:
    def register(self, phi, scope, assumptions, protocol, expiry):
        C = Claim(id=new_id(), phi=phi, S=scope, A=assumptions,
                  E=None, R=None, tau=expiry, h=None, status="registered")

        return C

    def accept(self, C, evidence, review):
        require frozen_protocol(C)
        require evidence.sources.isdisjoint(review.sources)    # 定义 315
        require replay(evidence) == replay(evidence, runtime="twin")  # 定义 313
        require review.power >= BETA_MIN and review.independence >= IOTA0
        C.status, C.E, C.R, C.h = "accepted", evidence, review, hash(...)
        return C

# IP-268 CDAG：单调撤稿传播
def retract(C, reason):
    q = deque([C])
    while q:
        c = q.popleft()
        if c.status != "retracted":
            c.status, c.retract_reason = "retracted", reason
            q.extend(c.children)                     # 全部后裔同步失效
    return reason

# IP-269/270 FUSE + IW：契约兼容与接口见证
def fuse(modules, dag):
    for (i, j) in dag.edges:
        delta = interface_residual(modules[i].contract.G,
                                   modules[j].contract.A, on=interface_vars(i, j))
        cov   = witness_coverage(fused, i, j)         # 融合后联合分布
        if delta > DELTA_MAX or cov < COV_MIN:
            fused.requires_adapter(i, j, delta)       # 或拒绝融合
    return fused

# IP-271 EP：涌现属性探针（跨模块时序对）
def probe_emergence(fused, psi, n):

    return empirical_risk(traces, psi), e_process(traces, psi)   # 定义 314

def claim_carrying_step(M, obs):

    Cs = M.ledger.minimal_cover(obs)
    if any(c.status != "accepted" for c in Cs):

            M.cdag.retract(c, reason="scope/expiry")
            return M.r68_fallback(obs, reason="scope")
    tau = M.pi_sigma.prefix_dispatch(mode.a[:k]) * lam
    return tau.with_claims({c.id for c in Cs})       # 可审计的行为证书

def meta_review(reviewers, third_party_probe):

## 4. 推导

**引理 19（融合不可加性）** 存在两个模块各自契约零误差（`ε_1=ε_2=0`），但融合后 `δ_12>0`（如毫秒/秒时延语义错配），使 `Risk(M_⊗)≥λ_12·δ_12>0`。故 `{Valid(K_i)}` ⇏ `Valid(K_⊗)`：系统级声明必须逐边见证，否则犯合成谬误。

**引理 20（审稿独立性与投毒放大）** 证据源重叠 `1−ι`、污染成功率 `δ_p`、重叠证据支持权重 χ 时，`Err ≥ (1−ι)·δ_p·χ`；`ι→1` 时 `Err≤ε_σ`。系：独立审稿是数量级安全，不是流程装饰；共享上游的「多源」不算多源。

**引理 21（撤稿传播的可靠、保守与僵尸免疫）** 传播 `O(V+E)`；失效集合 `Ret ⊇ A*`（可靠且保守）；要求新 id + 新预注册后，不存在同 id 复活，故无僵尸声明。

**定理 18（PEER 严格包含 FLUID）** 在 A99–A102（单模块、`δ=0`、`ε_emerge=0`、`ι=1`、`β≥β_min`、无撤稿）下，PEER 与 FLUID 逐指令相同；一般情形 `Risk_PEER ≤ Risk_FLUID + ε_review`，任何越界/撤稿都切到同一 λ_floor 兜底。FLUID 是 PEER 在「单模块 + 完美独立自审 + 无漂移」边界的退化，安全侧不让步。

**定理 19（融合安全上界与无突变）** 若全部接口见证覆盖、涌现探针通过、融合上界 `≤ε`，则融合系统在 `S_⊗` 内执行风险 `≤ε+ε_review+ε_scope`；撤稿使 λ 单调不降并切 R68 认证前缀，换装不变式保持 ⇒ 控制连续、无突变。

**定理 20（anytime-valid 与反 Goodhart）** (i) e-process 接受规则对任意自适应采样/停止保证错误接受率 `≤α` 且不随时长增长；(ii) 在 A103（reviewer 收益 = 负校准误差，校准用第三方探针）下，「缩小 scope 以求通过」不增加收益，Goodhart 通道被切断。

## 7. 本轮最大风险

**一句话**：PEER-RAS 把「系统说自己安全」升级为「一个审稿系统说它安全」，但如果审稿分布、接口见证与涌现探针都由同一套基础设施生成，整个声明 DAG 就会共享同一个**未被验证的接口/审稿盲区**——**技术融合把一张张『已接收』的论文叠成一座纸牌屋，而审稿通过只是让它看起来更像真的；最危险的不是没有证书，而是一叠互相引用、共同错误的证书。**

**次级风险与缓解**：审稿 theater/Goodhart（元审稿 + e-process + 校准型激励 + E312）；接口见证成本爆炸（变更/高风险边优先 + 影响分析 + E303）；撤稿抖动（分级撤稿 + 滞回 + E314）；预注册僵化（版本化预注册、新 id）；声明循环自证（拓扑检查 + 独立源）；复现不等于正确（明确边界 + 第三方涌现探针）。
