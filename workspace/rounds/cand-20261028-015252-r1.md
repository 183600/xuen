# 第 11 轮 · CORE-VLA：把持续学习写成任务家族课程，把多视角写成训练期几何

> 检索/复核日期：**2026-10-28（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API[S1]。本轮是灵感循环第 1 轮，状态文件续第 10 轮 FACT-VLA；三个灵感词是「持续学习」「人形机器人」「多视角视觉」。FACT-VLA 继续保留，但本轮把主火力从“接触相位”移到**跨任务的空间记忆与多视角几何**。

## 0. 先给结论：下一块短板是“跨任务的空间记忆”，不是“再换一个更大的 VLA”

本轮最重要的判断是：**在 32 个任务、5 类泛化轴、33,276 个 episode、10 组头部标定之间，真正稀缺的不是模型参数量，而是同一张 checkpoint 能否持续保持对象身份、3D 空间关系与旧任务能力。**

因此提出 **CORE-VLA**，四层共用一个 checkpoint：

- **C — Continual task-family curriculum + experience replay**：按 6–8 个任务家族顺序训练，保留约 2% 的分层 replay，用 LoRA 控制可塑性；与 joint training 做 A/B，不假设持续学习一定赢。
- **O — Object-view memory + bimanual roles**：用有界对象槽位记住“物体在哪、是否被遮挡、由哪只手主导”，并把双手角色显式化；不做完整 3D SLAM。
- **R — RGB-only training-time geometry + pose-aware multi-view tokens**：训练期用头部双目做深度/对应/跨视角动作一致性教师，推理只吃 RGB；腕部相机用 EE 位姿 + 学习到的腕-手外参注入相机几何。
- **E — Evidence-gated execution**：用多视角重投影不一致、对象槽位漂移、时序预测误差做不确定性，决定“继续执行 / 减速 / 重观察 / 回退”。

一句话：**把多视角变成训练期教师，把持续学习变成任务家族课程，把对象恒存变成有界槽位记忆，再用视角证据门控执行——这是本轮最值得押注的线。**

## 1. 这轮怎么想：三个词是一条链

### 1.1 人形机器人：G1 的四个视角不是“四个相同输入”

G1 + Dex1 的数据不是普通桌面单臂数据。官方 32 个 HF 数据集合计 **33,276 episodes / 18,282,246 frames / 169.28 h / 30 fps / 4 路相机**；每任务约 1,000 episodes，但时长从 **1.80 h 到 11.10 h**，相差约 6 倍；帧数最多的 10 个任务占 **46.3%** 的帧[S5][S6][D1]。

这带来两个直接后果：

1. **按帧均匀采样会系统性偏向长任务**。比赛按任务等权计分，HangCup（1.80 h）与 ToolboxStorage（11.10 h）不应该相差 6 倍训练权重。应按 **task-balanced → episode-balanced → phase-balanced** 采样，而不是 frame-uniform。
2. **四个视角的几何角色不同**。头部双目是**固定基座、已 rectified、有 R/T 标定**的立体对；左右腕部是**随手臂运动、只有内参、没有到头部显式外参**的 egocentric 视图[S6][D1]。把四路 token 直接拼接，模型很难知道“哪两路可以做极线约束、哪一路是移动相机”。

还有一个容易被忽略的负结果：本轮对 32 个 `meta/stats.json` 的统计显示，`action.pivot` 在大多数任务上接近静态（仅 4/32 的 max std > 0.02；OrganizeTools 0.147、StorePaddle 0.065、FoldTowel 0.060、PaperCupStacking 0.025），`lower_body` 虽在动但 action≈state，更像平衡控制器而不是自由工作空间自由度[D1]。**不要把“靠腰部/底盘移动扩展工作空间”当主路径**；G1 在这里是固定基座，人形特征主要体现在**双臂协调、头部双目、腕部移动视角**。pivot-aware 只作为这 4 个长任务的可选开关。

### 1.2 多视角视觉：把几何当老师，而不是把 token 拼起来

榜单头部三条公开路线恰好代表三种取舍[S8][S9][S10]：

- **MolmoAct2**（上一轮种子榜首 29.7%）：Molmo2-ER + FAST + flow matching，加 **10×10 自适应深度 token**（128 codes，只重算变化格）。深度是**场景级**的，不是对象级；没有持久对象记忆。
- **WALL-OSS-0.5**（28.5%）：4B（3B VLM + action expert），gradient-bridged pretraining；论文自述**单帧输入**，长程/遮挡记忆弱。
- **DreamZero**（27.9%）：14B World Action Model，联合视频/动作，约 **7 Hz**；零样本泛化强，但重、慢、视频可能幻觉，部署代价高。

它们共同的空白不是“没上多视角”，而是**没有把多视角几何变成可迁移的监督，也没有把对象身份跨时间保留下来**。而 2026 年的多篇工作已经证明：几何教师可以在**训练期**注入，推理零额外 FLOPs：

- **MVUCF**：训练期深度 + 跨视角对应，LIBERO 98.9、LIBERO-Plus +22.4、RoboTwin +23.3，推理零几何 FLOPs[S11]。
- **PEAfowl**：几何引导的多视角融合 + 训练期深度蒸馏，RoboTwin 约 +23pp[S12]。
- **跨视角动作一致性**：LIBERO-Plus +7.4pp；真实新相机 53.3% → 74.4%[S22]。
- **多视角演示**能提升单视角策略并突破数据缩放瓶颈，但“视角越多越好”不成立，存在有效区间[S24]。
- G1 上的 **active stereo ACT** 表明：数据有限时，最小主动双目可胜过复杂多传感器堆叠；共置头部相机会互相干扰[S21]。

所以本轮不押“更大的多视角融合网络”，而押 **MGD（Multi-view Geometry Distillation）+ PMT（Pose-aware Multi-view Tokenization）**：头部双目提供天然的动作等价视图对，腕部提供接触外观；训练时学几何，推理时只保留轻量相机位姿嵌入。

### 1.3 持续学习：不是上线后狂更新，而是训练时的任务家族课程 + 推理时的对象记忆

持续学习在机器人里常被讲成“部署后不断适应”。但本赛题更现实的两个层面是：

1. **参数层**：32 个异构任务联合训练会互相干扰；按任务家族顺序训练 + replay 可能比 joint 更好。2026 年真实世界 VLA 的 10 任务流实验给出了很强的证据：**sequential FT + experience replay 在同算力下显著优于 joint multi-task**（AS 97.2 vs 82.6/83.2），而 naive sequential FT 只有 31.4/38.3；2% buffer、0.2 replay frequency 就够[S13]。
2. **状态层**：即使参数不遗忘，episode 内的对象身份、遮挡状态、双手角色也会丢。比赛是 32 任务 × 10 trials 的流式真机评测，模型需要在**不更新参数**的情况下跨 episode 记住“这个物体刚才在哪、现在被哪只手挡住”。

预训练 VLA 对遗忘有一定抵抗，简单 ER 有时接近零遗忘；但这会随预训练规模和任务分布变化，不能假设[S14]。在持续 RL 设定下，Seq. FT + LoRA 被报告为高可塑性、几乎不遗忘，并常在零样本泛化上超过多任务 oracle；但这是 on-policy RL 的结果，不能直接外推到行为克隆[S15]。phase-aware replay 说明**按接触相位分层 replay**比均匀 replay 更有效[S16]；LifelongVLA 的双时间尺度 LoRA 相对 ER 提升 13.0 SR、降低 8.2 forgetting[S17]。

因此本轮把“持续学习”拆成两件事：

- **训练时**：TFC-ER（Task-Family Curriculum + Experience Replay），按任务家族顺序训练，replay 按家族/相位/视角分歧分层；与 joint 做门控对比。
- **推理时**：OVM（Object-View Memory）+ BRA（Bimanual Role Assignment），用有界对象槽位和角色 token 维持跨帧/跨 episode 的一致性；不更新策略权重。

再加一个“几何 rehearsal”：几何不变性（深度、对应、跨视角动作一致）是**任务无关**的，可以在当前任务数据上持续练习，不一定需要旧任务像素。这正好补上 replay 的样本效率问题。

### 2.2 API v2

以 raw main / git clone 为准（commit `edd0a1c`，2026-10-28）[S4]：

- 观测只有 4 路 RGB + 左右臂关节 + EE 位姿 + 夹爪 + 下身体 + 语言；**没有 depth/torque/current/tactile/force**。

### 2.3 数据

- 32 个任务，**33,276 episodes / 18,282,246 frames / 169.28 h / 30 fps / 4 相机**，约 **811 GB**，AV1 编码，原生 640×480[S5][S7][D1]。
- 每任务 episodes 969–1533（中位数约 1026.5），时长 1.80–11.10 h（中位数约 4.77 h）；平均 episode 6.2–37.6 s，中位数 16.2 s[D1]。
- 帧数 top10 任务占 46.3%，最高单任务 6.6%；**按帧采样会偏**。
- `meta/info.json` 的 `camera_params` 给出头部双目 rectified 内参、畸变、R/T；32 个 repo 中有 **10 组不同的头部标定**（fx 约 186.03–296.15，|Tx| 约 46.42–63.24）[D1]。验证必须按标定组切分，不能随机按帧切。
- 每个任务的 `meta/tasks.parquet` 有 **5 条英文复述**，适合做语言鲁棒性/leave-one-paraphrase-out[D1]。
- 腕部只有 RGB 内参，没有到头部/基座的显式外参；腕-手外参需要估计或学习[D1]。
- `action.pivot` 在大多数任务上接近静态（4/32 有明显变化）；`lower_body` 的 action≈state，更像平衡控制器；**不要把 torso locomotion 当主路径**[D1]。

| 方案 | 公开做法 | 本轮判断的瓶颈 |
|---|---|---|
| MolmoAct2 | Molmo2-ER + FAST + flow matching + 10×10 自适应深度 token | 深度是场景级，缺对象级持久记忆；2D 网格丢精细接触几何 |

**结论**：榜首 <30% 说明“感知-接触-长程”仍有大量失败；下一波增益更可能来自**空间记忆与多视角几何**，而不是单纯把 backbone 换大。

## 3. 为什么不是其他路线

| 路线 | 为什么本轮不做 |
|---|---|
| 完整 World Model / DreamZero 复刻 | 14B、7 Hz、视频生成；比赛要低延迟、单模型、可回退，收益/代价不划算 |
| 在线 TTT / RL / 自适应 | 无标签、无 reward、真机试错成本高；规则与可信度风险大[S27] |
| 触觉/力/力矩 | API 不提供；第 10 轮已改成接触相位代理 |
| 完整 3D SLAM / NeRF / Gaussian | 桌面固定场景，过重；对象槽位足够 |
| 盲目多视角 concat | 共置头部相机会干扰；腕部是移动相机；需要位姿与几何约束 |
| EWC / 复杂 adapter 路由 | 先做最简单的 ER + LoRA；复杂 CL 在 32 任务上未必划算 |
| 多模型 ensemble | 赛道要求通才单模型；N 端口并发也扛不住 |
| 靠 pivot/腰部移动扩展工作空间 | 大多数任务 pivot 静态，只有 4/32 有明显变化；可做任务条件开关，但不作为主路径 |

## 4. CORE-VLA：四层，一个 checkpoint

### 4.1 R 层：MGD + PMT——训练期几何，推理期只留位姿

**MGD（Multi-view Geometry Distillation）**

- 输入：头部双目 `head_stereo_left/right`（已 rectified）；腕部 `wrist_left/right` 作为外观/接触视图。
- 教师信号（全部来自官方数据，不引入外部数据）：
  1. **立体深度**：对头部双目做 SGBM / 轻量立体匹配，得到稀疏/半稠密深度；透明物体失败时降权。
  2. **跨视角对应**：同一场景在左右目中的 patch 对应；用极线约束/循环一致性过滤。
  3. **跨视角动作一致性**：头部左右目是同一状态的动作等价视图对；对两路分别做 flow matching，约束预测速度在机器人动作空间一致。
- 学生：在 VLM/动作专家之间加轻量深度头与对应头；训练后**移除**，推理只保留被几何正则化过的视觉 token。
- 预期：零推理 FLOPs 的几何先验；对位置/相机/背景偏移更稳。
- 风险：头部双目在 API 上是否与数据集同一物理对（假设 A1，需单任务调试确认）；透明/反光物体立体失败；标定漂移。

**PMT（Pose-aware Multi-view Tokenization）**

- 每个 view token 加相机嵌入：
  - 头部：固定外参 + 内参；
  - 腕部：EE 位姿 + **可学习的腕-手外参**（初始化自机器人运动学/CAD，训练中优化）；
  - 相机 ID / view type embedding。
- 用 Plücker ray / 投影位置编码注入几何，而不是让模型从像素猜相机关系。
- 训练时做 **view dropout**（随机丢头部或腕部）与位姿噪声，避免过拟合单一视角。
- 预期：腕部移动相机不再被当成静态相机；跨视角对应更稳；对视角缺失更鲁棒。
- 风险：EE 位姿坐标系与相机坐标系不一致；腕-手外参不可观；需要消融确认增益。

### 4.2 C 层：TFC-ER——任务家族课程 + 分层 replay

- 将 32 个任务聚成 6–8 个家族（示例）：
  - 插入/接触：PlugCharger、PlugInEthernet、DisconnectEthernet、Unlock、SyringeWaterTransfer；
  - 可变形：FoldTowel、ZipUp、PackBag、PackDoll；
  - 双手交接/堆叠：ArrangePlates、StackBowls、ToolboxStorage、StorePaddle、PaperCupStacking；
  - 分类/整理：ColorArrangement、FruitSorting、OrganizeStationery、OrganizePencilCase、OrganizeBookshelf、OrganizeTools；
  - 精细放置：PlacePhotoFrame、StoreEarphones、PackPhone、RemovePinnedNote、PourOutMedicine；
  - 长程组合：ToolboxStorage、StorePaddle、SpellRobot、PackPhone、FoldTowel、OrganizeTools。
- 顺序训练，每个家族 1–2 个 epoch；共享视觉/几何 backbone 冻结或低秩更新，动作专家/LoRA/槽位头更新。
- Replay：
  - 约 **2% episodes**（约 665 个）分层保留：家族均衡、接触相位均衡、视角分歧高的样本优先；
  - replay 混入比例约 20%；若遗忘 >2pp，提高到 30–40%；
  - 几何 rehearsal：在当前任务数据上继续算深度/对应/跨视角动作一致损失，作为任务无关锚点。
- 对照：同数据、同算力的 **joint 32-task training**；若 joint 更好，保留 joint，只取 MGD/OVM/VGE。**持续学习是待验证假设，不是信仰。**
- 风险：任务家族划分主观；顺序敏感；replay 仍有偏；工程复杂度高于 joint。

### 4.3 O 层：OVM + BRA——对象恒存与双手角色

**OVM（Object-View Memory）**

- 从多视角 token 预测 **16–32 个对象槽位**，每个槽位含：
  - 存在/可见概率；
  - 基座系 3D 位置/尺度（来自头部双目深度，或轻量深度头）；
  - 外观原型（视觉 embedding）；
  - 语言/角色 embedding；
  - 交互状态（free / grasped / placed / occluded）；
  - 最后可见时间。
- 跨帧用 3D 距离 + 外观相似度做 Hungarian 匹配；暂时不可见则保留为 `occluded`，超过 TTL 才删除；新区域解释不了时新建槽位。
- 训练标签：
  - 优先 **自监督 slot attention**（多视角重建 + 对比 + 稀疏/多样性正则），不引入外部模型；
  - 若规则允许，可用 SAM2/GroundingDINO 只在训练期生成伪标签，**不部署**；规则默认外部数据 OFF 时不用。
- 原型库：离线聚类训练槽位，存每类对象/角色的原型；推理时检索最近原型，用于语言 grounding 与 novelty 检测；无梯度更新。
- 输出给动作专家：槽位 token + 槽位相对 EE 位置 + 预测的对象位移；可加“操作哪个槽位”的辅助头。
- 结果校验：执行 chunk 后，比较预测槽位状态与观测；不一致则触发 VGE 恢复。
- 风险：透明/可变形物体槽位不稳；槽位漂移；深度头延迟；外部伪标签合规性。

**BRA（Bimanual Role Assignment）**

- 角色：左主导 / 右主导 / 双手协同 / 左稳定 / 右稳定 / 空闲。
- 从语言 + 槽位 + 当前相位预测角色 token，条件化动作专家；对双手同时活跃的片段加跨臂相对位姿/速度一致性损失。
- 弱标签来自 EE 运动、夹爪开合、接触相位；不需要人工标注。
- 预期：交接、堆叠、折叠、拉拉链等双手任务更稳；单臂任务退化为原策略。
- 风险：角色歧义；弱标签噪声；单臂任务过拟合“双手”先验。

### 4.4 E 层：VGE——视角证据门控执行

- 不确定性来源（全部廉价）：
  1. 头部双目/腕部特征的重投影不一致；
  2. 对象槽位漂移/突然消失；
  3. 动作 chunk 的时序预测误差（若保留轻量未来头）；
  4. 接触相位与视觉接触不一致（接第 10 轮 FACT-VLA）。
- 决策：
  - 低不确定：正常执行 chunk 的可靠前缀；
  - 中不确定：减速、缩短 chunk、请求更高分辨率腕部/历史帧；
  - 高不确定：暂停、重观察、回退到安全端点/恢复策略。
- 阈值在 held-out 标定组/扰动集上校准，优化 **false alarm vs escape**；不能一有噪声就停。
- 预期：减少“自信地做错”；提升长程与遮挡任务的成功率；延迟只在高不确定时增加。
- 风险：阈值难校准；频繁减速拉低 step score；视角全遮挡时无信号。

### 4.5 接口工程：多速率观测 + N 端口并发

- 用 `obs_delta_indices` 做多速率：
  - 头部双目：较低分辨率 + 历史（几何/对象记忆）；
  - 腕部：较高分辨率 + 当前（接触/精细操作）；
  - 语言/本体：当前。
- 用 `image_resize` 在评测端缩放，减少带宽；注意缩放后内参要同步，否则 PMT/MGD 的几何会错。
- N 端口：
  - 单 GPU 共享后端 + 每端口状态字典（历史、槽位、相位、VGE 阈值）；
  - 请求调度器做小批量合并，设最大等待窗口；`reset` 只清该端口；
  - 线程安全/异步；p99 延迟预算；chunk 前缀执行，尾部保持/安全端点。
- 这是“接口工程”创新，不是模型创新，但直接决定 N 台机器人并发时是否崩。

### 4.6 与第 10 轮 FACT-VLA 的关系

- **FACTOR / CPT / CAC** 保留：接触相位、柔顺行为克隆、chunk 边界截断仍是接触密集任务的核心。
- **EGP 更新**：单任务调试可用于 probe；计分提交仍是全 32；榜单 Coming Soon 时不用种子数据做 SOTA 声明。
- **新增**：MGD/PMT（空间几何）、TFC-ER（跨任务参数）、OVM/BRA（对象与双手状态）、VGE（视角证据）。
- **DGS-32C → DGS-32V**：在原有任务/相位/语言切片上，加**标定组、视角缺失、遮挡、对象恒存、遗忘**切片。
- 一句话：**FACT-VLA 管“怎么碰”，CORE-VLA 管“东西在哪、还在不在、以前会的还记不记得”。**

## 5. 实验与门控

| Gate | 问题 | 最小实验 | 通过标准 | 失败则 |
|---|---|---|---|---|
| G0 | API 头部双目是否同一立体对？ | 单任务调试抓图，检查重叠/极线/视差 | 可稳定匹配；标定与数据一致 | 退回单目深度/2D 对应，MGD 降级 |
| G1 | MGD 是否真的有用？ | 同 backbone，±MGD，held-out 标定组/视角扰动 | 平均 +2pp，或视角扰动 +5pp；推理延迟不增 | 只保留 PMT 或砍掉 |
| G2 | 持续课程是否优于 joint？ | joint vs TFC-ER，同算力，held-out 家族 | 平均 +2pp 或遗忘 −3pp | 保留 joint，只取其他层 |
| G3 | OVM 是否解决遮挡/对象恒存？ | 遮挡/移出视野/干扰物切片 | +3pp；槽位跟踪误差下降 | 缩到 8 槽位或砍掉 |

| G5 | VGE 是否减少自信错误？ | 扰动集 + 真机 debug | 失败率下降；误停 <5% | 提高阈值/只保留重观察 |
| G6 | 接口是否扛住 N 端口？ | N 端口并发压测 | p99 在预算内；状态不串 | 减功能/加副本/降分辨率 |
| G7 | 全量是否值得提交？ | 32 任务 × 10 trials 配对 | +3pp 现实，+5pp 冲刺 | 提交安全版 |

**注意统计功效**：32×10 = 320 trials，p=0.5 时 SE ≈ 2.56pp；+5pp 需要配对设计或多轮。不要把 +2pp 的噪声当突破。

## 6. 风险、合规与开关

- **单模型合规**：MGD/OVM/BRA/VGE 全部共享同一 checkpoint；不部署外部在线模型；离线伪标签需按规则确认。
- **外部数据**：默认 OFF；MGD 教师来自官方双目，不引入外部深度数据。
- **API 假设**：头部相机名与数据集 `head_stereo` 同一物理对是 A1，必须先用单任务调试验证。
- **标定漂移**：10 组标定组；按组切分验证；PMT 注入位姿而不是死记像素。
- **透明/反光/可变形**：立体失败时降权，改用对应/外观；OVM 槽位加 TTL 与不确定性。
- **延迟**：MGD 头推理时移除；OVM/VGE 轻量；多速率观测；chunk 前缀执行。
- **可信度**：不把种子榜单当 SOTA；不声称未复现的 +20pp；所有数字标来源与条件。
- **安全**：VGE 高不确定时回退安全端点；N 端口状态隔离；异常动作限幅/超时。

## 7. 一句话押注

**用头部双目做训练期几何教师（MGD），用位姿感知的多视角 token（PMT）把腕部移动相机讲清楚，按任务家族做持续训练 + 2% 分层 replay（TFC-ER），再加有界对象槽位/双手角色（OVM/BRA）与视角证据门控（VGE）——在同一个 WLA-1.0-Base checkpoint 上同时解决多视角几何、任务干扰和对象恒存，这是本轮最值得押注的线。**

# 第 11 轮产物区 · CORE-VLA 技术报告（Continual Object-centric RGB-only Evidence VLA）

> 目标赛事：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。检索/复核日期：**2026-10-28（UTC）**。本报告承接第 10 轮 FACT-VLA，但主火力转向**跨任务的空间记忆、多视角几何与持续学习**。所有榜单数字、论文数字与本地统计均标注来源与条件；不能独立复核的内容明确标为“上一轮工作假设”。

## 0. 产物摘要

**核心命题**：榜首成功率不到 30%，说明“更大的 VLA”不是唯一瓶颈；真正的短板是同一张 checkpoint 在 32 个任务、5 类泛化轴、10 组头部标定之间，能否持续保持**对象身份、3D 空间关系与旧任务能力**。

**方案**：CORE-VLA，四层共用一个 checkpoint：

1. **C — TFC-ER**：任务家族课程 + 分层 experience replay + LoRA；与 joint training 做同算力 A/B。
2. **O — OVM + BRA**：有界对象槽位记忆 + 双手角色 token；不做完整 3D SLAM。
3. **R — MGD + PMT**：训练期头部双目几何教师（深度/对应/跨视角动作一致）+ 位姿感知多视角 token；推理只吃 RGB。
4. **E — VGE**：用多视角重投影、槽位漂移、时序预测误差做证据门控执行。

**主押注**：MGD + TFC-ER 是两条主实验线；OVM/BRA 是差异化层；VGE 是运行时安全层；FACT-VLA 的接触相位继续保留。

**明确不做**：完整 world model / DreamZero 复刻、在线 TTT/RL、触觉/力/力矩、完整 3D SLAM/NeRF/Gaussian、盲目多视角 concat、复杂 CL、多模型 ensemble、靠 pivot/腰部移动扩展工作空间（仅 4/32 任务有明显 pivot 变化，不作主路径）。

### 1.2 API v2 契约

以 raw main / git clone 为准（commit `edd0a1c`，README 标注 “version 2”）[S4]：

- `metadata` 字段：`control_space`、`obs_delta_indices`、`image_resize`、`action_chunk_size`、`token`。
- `obs_delta_indices`：key 决定实际发送哪些观测；value 是相对当前帧的偏移（旧→新，≤0，严格递增）；历史不足用首帧填充；**只有声明的 key 会发送**。
- `image_resize`：评测端缩放，`[height, width]`；默认原始 480×640。
- `action_chunk_size`：服务端返回的动作 chunk 长度；客户端可执行前缀。
- N 台测试机器人：随机顺序、从 `8765` 起连续端口；可每端口独立进程/模型副本，也可共享后端（必须并发调度 + 状态隔离）；调用并发；必须按端口隔离 episode 状态、线程安全。`meta.token` 每一步都要返回。
- §6 会记录延迟、动作可变性、动作规律性，可能在展示页体现；慢和抖是可信度问题。
- 观测：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB；左右臂关节 `[7]`、EE 位姿 `[6]`、夹爪 `[1]`、下身体 `[15]`、语言 `str`。
- **没有 depth / torque / current / tactile / force**。

工程含义：

1. `obs_delta_indices` 允许**多速率观测**（头部低分辨率+历史，腕部高分辨率+当前）。
2. `image_resize` 会改变内参；若做 PMT/MGD，必须同步缩放内参，否则几何全错。
3. N 端口并发下，单 GPU 共享后端必须有**每端口状态字典**与线程安全调度；`reset` 只能清该端口。
4. 动作 chunk 不能盲执行到底；要按 VGE/接触相位截断，尾部保持/安全端点。

### 1.3 数据

- 32 个 HF 数据集，**33,276 episodes / 18,282,246 frames / 169.28 h / 30 fps / 4 相机**，约 **811 GB**，AV1，原生 640×480[S5][S7][D1]。
- features：`head_stereo_left/right`、`wrist_left/right`；另有左右臂关节、EE 位姿、夹爪、下身体、语言。
- `meta/info.json` 的 `camera_params` 给出头部双目 rectified 内参、畸变、R/T；32 个 repo 中有 **10 组不同头部标定**（fx 约 186.03–296.15，|Tx| 约 46.42–63.24）[D1]。
- 每任务 episodes 969–1533（中位数约 1026.5）；时长 1.80–11.10 h（中位数约 4.77 h）；平均 episode 6.2–37.6 s（中位数 16.2 s）[D1]。
- 帧数 top10 任务占 **46.3%**；最高单任务 6.6%。按帧均匀采样会偏向长任务。
- 每个任务的 `meta/tasks.parquet` 有 **5 条英文复述**；适合语言鲁棒性/leave-one-paraphrase-out[D1]。
- 腕部只有 RGB 内参，没有到头部/基座的显式外参；腕-手外参需估计或学习[D1]。
- `action.pivot` 在大多数任务上接近静态：32 个任务中只有 4 个 max std > 0.02（OrganizeTools 0.147、StorePaddle 0.065、FoldTowel 0.060、PaperCupStacking 0.025）；`lower_body` 虽在动，但 action≈state，更像平衡控制器，不是自由工作空间自由度[D1]。**不要把“靠腰部/底盘移动扩展工作空间”当主路径；可对 4 个长任务做 pivot-aware 可选开关。**

### 1.4 头部方案与瓶颈

| 方案 | 公开做法 | 本轮判断的瓶颈 |
|---|---|---|
| MolmoAct2 | Molmo2-ER + FAST + flow matching + 10×10 自适应深度 token（128 codes，只重算变化格） | 深度是场景级，不是对象级；无持久对象记忆；2D 网格丢精细接触几何 |
| WALL-OSS-0.5 | 4B（3B VLM + action expert），gradient-bridged pretraining | 论文自述单帧输入，长程/遮挡弱；动作维度与 G1 需适配 |

**结论**：榜首 <30% 不是“模型不够大”，而是“感知-接触-长程”仍有大量失败。公开头部方案没有把**对象级持久记忆 + 多视角几何 + 持续任务训练**合到一个轻量运行时里，这是本轮切入点。

### 1.5 持续学习证据

- **真实世界 VLA 的 10 任务流**：sequential FT + experience replay 在同算力下显著优于 joint multi-task（AS 97.2 vs 82.6/83.2）；naive sequential FT 只有 31.4/38.3；2% buffer、0.2 replay frequency 就够[S13]。
- **预训练 VLA 对遗忘有抵抗**：简单 ER 有时接近零遗忘；但会随预训练规模/任务分布变化，不能假设[S14]。
- **持续 RL 中的 Seq. FT + LoRA**：被报告为高可塑性、几乎不遗忘，并常在零样本泛化上超过多任务 oracle；但这依赖大预训练模型 + PEFT + on-policy RL，不能直接外推到行为克隆[S15]。
- **Phaser**：按接触相位分层 replay 比均匀 replay 更有效；要避免 phase starvation[S16]。
- **LifelongVLA**：双时间尺度 LoRA + cache-efficient replay，相对 ER 提升 13.0 SR、降低 8.2 forgetting[S17]。
- **ReGen**：用 world model 生成伪 replay，减少遗忘约 50%，但长程视觉会退化；只作为可选，不作为主路径[S28]。

**含义**：先做最简单的 **ER + LoRA + 任务家族顺序**，不要一上来 EWC/adapter 路由；replay 要按家族/相位/视角分歧分层；几何不变性可作为任务无关 rehearsal。

### 1.6 多视角证据

- **MVUCF**：训练期深度 + 跨视角对应，LIBERO 98.9、LIBERO-Plus +22.4、RoboTwin +23.3，推理零几何 FLOPs[S11]。
- **PEAfowl**：几何引导多视角融合 + 训练期深度蒸馏，RoboTwin 约 +23pp[S12]。
- **跨视角动作一致性**：LIBERO-Plus +7.4pp；真实新相机 53.3% → 74.4%[S22]。
- **多视角演示**能提升单视角策略并突破数据缩放瓶颈，但“视角越多越好”不成立[S24]。
- **G1 上的 active stereo ACT**：数据有限时，最小主动双目可胜过复杂多传感器堆叠；共置头部相机会互相干扰[S21]。
- **VersaCamVLA**：相机可配置、任意位姿输入，对相机数量和位姿变化更鲁棒[S23]。
- **MuCoLA**：多视角一致 latent action，谱滤波，视角不变性[S25]。
- **对象/空间记忆**：OCC4M 的对象中心 4D memory、out-of-vision 空间记忆、MEM 的多尺度具身记忆，均支持“对象恒存/遮挡”是独立瓶颈[S18][S19][S20]。
- **RoboMME**：系统评测记忆对机器人策略的影响，说明记忆不是附属品[S26]。

**含义**：不要盲目 concat 四路 token；要用**几何教师 + 相机位姿 + 视角 dropout + 多视角一致性**。头部双目天然提供动作等价视图对，是 UniBot 数据里被低估的监督源。

**含义**：

1. **episodes 近似均衡，frames 不均衡**。按 episode 采样接近任务等权；按 frame 采样会让 ToolboxStorage 的权重是 HangCup 的 6 倍。比赛按任务等权计分，应使用 **task-balanced → episode-balanced → phase-balanced** 采样。
2. **长任务帧多但 trial 数相同**。长任务并不因为帧多而获得更多评测权重；训练时应防止短任务欠拟合。
3. **平均 episode 中位数 16.2 s**，但最长 37.6 s；chunk=30（约 1 s）时，一个 episode 约 6–38 个 chunk。VGE 的 chunk 截断/重观察频率要按任务时长自适应。

### 2.2 标定组与验证切分

- 32 个 repo 的头部双目标定分成 **10 组**（fx、baseline、R/T 接近的归为一组）[D1]。
- 不能随机按帧切验证：同一 episode 的相邻帧、同一标定组的图像高度相关，会泄漏。
- 建议：
  - **GroupKFold by calibration group**：留 2–3 组做验证；
  - **Task-family holdout**：留 1–2 个家族做 unseen-family 测试；
  - **Language leave-one-paraphrase-out**：每任务留 1 条复述；
  - **View perturbation**：丢头部/腕部、加遮挡、换分辨率；
  - **Temporal holdout**：用 episode 后 20% 做长程测试。

### 2.3 语言复述

- 每任务 5 条英文复述；同一任务的动作分布相同，但措辞/物体指代不同[D1]。
- 用法：
  - 训练时随机采一条，做语言 dropout；
  - 验证时 leave-one-paraphrase-out，测语言泛化；
  - 把复述与对象槽位做对比学习，避免策略只记住固定句式。

### 2.4 负结果与不确定项

- **pivot 多数任务静态、lower_body 是平衡控制器**：不要把 torso locomotion 当主路径；只对 4/32 有明显 pivot 变化的任务做可选开关。
- **腕部无外参**：不能直接算腕-头度量对应；需要手眼标定或学习外参。
- **样本 episodes 无显式 session ID**：上一轮“192 sessions”的说法在本轮抽查中未确认；不要把它写成硬事实。
- **榜单 JSON 不可用**：当前只能引用上一轮种子；不能声明当前 SOTA。
- **API 相机名与数据集相机名**：`cam_left_high/right_high` 是否就是 `head_stereo_left/right`，尚未真机验证；列为假设 A1。
- **透明/反光物体**：立体匹配会失败；MGD 需降权/改用对应与外观。

### 2.5 对方法的含义

| 维度 | 数据/接口事实 | 方法含义 |
|---|---|---|
| 数据采样 | episodes 均衡、frames 6× 差 | task/episode/phase 平衡采样，不用 frame-uniform |
| 多视角 | 头部双目 rectified + 10 组标定；腕部无外参 | MGD 主用头部双目；PMT 学习腕-手外参；按标定组验证 |
| 语言 | 每任务 5 条复述 | 语言 dropout + leave-one-out；槽位-语言对比 |
| 人形 | 固定基座、双臂；pivot 多数静态，4/32 有明显变化；lower_body 随动 | 做 BRA 双手角色；pivot-aware 仅作任务条件开关 |
| 接口 | obs_delta_indices/image_resize/N 端口 | 多速率观测 + 状态隔离 + 延迟预算 |
| 评测 | 32×10，SE≈2.56pp | 不追 +2pp 噪声；主看 +3–5pp 与配对设计 |

## 3. 方法

### 3.1 问题形式化

把每个 episode 建成部分可观测过程：

- 观测 `o_t = {I_t^headL, I_t^headR, I_t^wristL, I_t^wristR, q_t^arm, p_t^EE, g_t, q_t^lower, l}`。
- 动作 `a_t = {a_t^pivot[7], a_t^left_arm[7], a_t^left_EE[6], a_t^left_grip[1], a_t^right_arm[7], a_t^right_EE[6], a_t^right_grip[1], a_t^lower[15]}`，共 54 维；状态 60 维。
- 策略 `π(a_{t:t+H} | o_{≤t}, l; θ, M_t)`，`H=30`；`M_t` 是有界对象/角色记忆。
- 任务集合 `T = {T_1..T_32}`，任务家族 `F = {F_1..F_K}`，`K≈6–8`。
- 目标：最大化任务等权成功率，其次 step score / 交互质量；约束延迟、动作规律性、安全。

### 3.2 CORE-VLA 总览

```text
RGB + proprio + language
        │
        ├─ PMT: camera pose / ray embedding / view-type token
        │
        ├─ Shared VLM backbone (WLA-1.0-Base 6B, frozen or LoRA)
        │        │
        │        ├─ MGD heads (training only): depth / correspondence / cross-view velocity
        │        ├─ OVM head: object slots + visibility + 3D position
        │        ├─ BRA head: bimanual role token
        │        └─ Action expert: flow matching, chunk H=30
        │
        ├─ VGE: uncertainty from reprojection / slot drift / temporal error
        │
        └─ Runtime: multi-rate obs, chunk prefix, per-port state, safe fallback
```

训练期：MGD 头 + 几何损失 + 动作流匹配 + 槽位/角色辅助损失。
推理期：移除 MGD 头；保留 PMT 嵌入、槽位头、角色头、VGE；单 checkpoint。

### 3.3 R 层：MGD + PMT

#### 3.3.1 立体深度教师

对头部双目 `(I^L, I^R)`，用 SGBM / 轻量立体匹配得到视差 `d`，深度 `z = f_x * B / d`。用左右重投影/光度一致性过滤：

```text
L_depth = Σ_{p∈valid} ρ( z(p) - z_teacher(p) ) + λ_s * smoothness(z)
valid = photometric_consistency(I^L, warp(I^R, d)) > τ
```

透明/反光/无纹理区域 `valid=0`，不强行监督。

#### 3.3.2 跨视角对应

对左右目 patch 特征 `f^L_i, f^R_j`，用极线距离 + 循环一致性构造正样本，InfoNCE：

```text
L_corr = -Σ_i log exp(sim(f^L_i, f^R_{π(i)})/τ)
         / Σ_j exp(sim(f^L_i, f^R_j)/τ)
```

`π(i)` 由极线 + 深度/视差得到；循环一致性过滤误匹配。

#### 3.3.3 跨视角动作一致性

头部左右目是同一状态的动作等价视图。对两路分别做 flow matching，预测速度 `v^L, v^R`；在动作空间对齐：

```text
L_act = || v^L - v^R ||_2^2  (或 stop-gradient 对称版本)
L_FM  = || v^L - (a - ε) ||^2 + || v^R - (a - ε) ||^2
```

这不是“让两路特征一样”，而是**让同一动作在兩路视图下预测一致**；对相机/视角偏移更稳。

#### 3.3.4 总损失

```text
L_MGD = λ_d L_depth + λ_c L_corr + λ_a L_act + λ_f L_FM
```

训练后移除 depth/correspondence 头；动作专家保留被几何正则化的视觉 token。MGD 的推理 FLOPs = 0（与 MVUCF 同思路）[S11]。

#### 3.3.5 PMT：位姿感知 token

- 头部：固定外参 `T_head←base`，内参 `K_head`；每个 patch 加 Plücker ray `(d, m)`。
- 腕部：`T_wrist←base = T_EE←base * T_wrist←EE`；`T_wrist←EE` 可学习，初始化自 CAD/运动学。
- 每个 token：`e = e_visual + e_ray + e_viewtype + e_camid`。
- 训练扰动：view dropout（p=0.1–0.2）、位姿噪声、分辨率随机缩放（同步内参）。
- 推理：EE 位姿来自 API；腕-手外参从 checkpoint 读取；无需额外传感器。

**为什么不是普通位置编码**：普通 2D 位置编码不知道相机在哪；腕部相机随手臂移动，同一像素在不同时刻对应不同 3D 点。Plücker/相机位姿嵌入让模型能区分“头部固定视角”与“腕部移动视角”，并支持跨视角对应。

### 3.4 C 层：TFC-ER

#### 3.4.1 任务家族

建议 6–8 个家族（可按聚类/人工调整）：

| 家族 | 任务示例 | 主要挑战 |
|---|---|---|
| 插入/接触 | PlugCharger, PlugInEthernet, DisconnectEthernet, Unlock, SyringeWaterTransfer | 精细对准、接触相位、柔顺 |
| 可变形 | FoldTowel, ZipUp, PackBag, PackDoll | 形变、双手、长程 |
| 双手交接/堆叠 | ArrangePlates, StackBowls, ToolboxStorage, StorePaddle, PaperCupStacking | 角色分配、稳定性、长程 |
| 分类/整理 | ColorArrangement, FruitSorting, OrganizeStationery, OrganizePencilCase, OrganizeBookshelf, OrganizeTools | 对象身份、位置泛化、多物体 |
| 精细放置 | PlacePhotoFrame, StoreEarphones, PackPhone, RemovePinnedNote, PourOutMedicine | 小物体、遮挡、精度 |
| 长程组合 | ToolboxStorage, StorePaddle, SpellRobot, PackPhone, FoldTowel, OrganizeTools | 记忆、子目标、错误恢复 |

（家族有重叠是故意的：一个任务可属于多个家族；训练时按主家族排序，replay 时按多标签分层。）

#### 3.4.2 训练算法

```text
Input: task families F_1..F_K, replay buffer B (2% episodes), LoRA params
for k = 1..K:
    D_k = episodes of F_k
    for epoch in 1..E_k:
        for batch in D_k:
            batch = batch ∪ sample(B, ratio=0.2)
            L = L_FM + λ_s L_slot + λ_r L_role + λ_g L_geometry(current batch)
            update action expert / LoRA / slot+role heads; backbone frozen or low-rank
        evaluate all seen families on held-out calibration groups
        if forgetting > 2pp: increase replay ratio / add geometry rehearsal
    B = stratified_update(B, D_k, family_balance, phase_balance, view_disagreement)
```

- LoRA：rank 32/64，作用于动作专家 + 最后视觉块；backbone 主体冻结。
- Replay：约 2% episodes（约 665 个），按家族/相位/视角分歧分层；混入 20%。
- 几何 rehearsal：当前任务数据上继续算 `L_depth + L_corr + L_act`，不需要旧任务像素。
- 对照：同数据、同算力 joint 32-task；若 joint 更好，保留 joint，只取其他层。
- 评估：平均成功率、BWT（旧任务遗忘）、FWT（新任务前向迁移）、per-family 曲线。

#### 3.4.3 为什么可能赢 joint

- 32 个任务梯度方向冲突；顺序训练 + replay 降低干扰。
- 真实世界 VLA 证据支持“sequential + ER > joint”（同算力）[S13]。
- 几何 rehearsal 是任务无关正则，补 replay 的样本效率。
- LoRA 在持续 RL 中报告低遗忘；行为克隆仍需 ER 兜底[S15][S13]。
- **但这不是必然**：如果 1k episodes/task 的联合数据足够、任务共享多，joint 可能更好；所以必须 A/B。

### 3.5 O 层：OVM + BRA

#### 3.5.1 对象槽位

每个时刻维护 `N_s=16–32` 个槽位：

```text
s_i = { p_i ∈ R^3,  q_i ∈ R^6 (extent/pose),  e_i ∈ R^d (appearance),
        u_i ∈ [0,1] (visibility),  r_i ∈ R^d (role/language),
        state_i ∈ {free, grasped, placed, occluded},  t_i (last seen) }
```

- 从多视角 token + 深度预测槽位；用 Hungarian matching 跨帧关联。
- 匹配代价：`α||p_i - p_j|| + β(1 - cos(e_i, e_j)) + γ||q_i - q_j||`。
- 未见槽位保留 `TTL`（例如 2–5 s）；超过 TTL 删除；新区域解释不了时新建。
- 原型库：离线对训练槽位聚类，存每类对象/角色原型；推理检索最近原型，用于语言 grounding / novelty。
- 动作专家条件：槽位 token + 槽位相对 EE 位置 + 预测对象位移；辅助头预测“操作哪个槽位”。

#### 3.5.2 训练标签

- 首选 **自监督 slot attention**：多视角重建 + 对比 + 稀疏/多样性正则；不引入外部模型。
- 若规则允许：SAM2/GroundingDINO 只在训练期生成伪标签，不部署；外部数据默认 OFF 时不用。
- 语言 grounding：槽位 embedding 与任务复述/角色 embedding 做对比学习。
- 槽位监督不是必须逐像素；可用对象中心的一致性/预测损失。

#### 3.5.3 BRA 双手角色

- 角色集合：`left_lead, right_lead, both, left_stabilize, right_stabilize, idle`。
- 输入：语言 + 槽位 + 接触相位 + 双臂 EE 相对位姿；输出角色 token，条件化动作专家。
- 弱标签：EE 运动方向/速度、夹爪开合、接触相位、对象槽位位移。
- 辅助损失：角色分类 + 双手活跃时的跨臂相对位姿/速度一致性。
- 评估：双手任务子集（ArrangePlates、StackBowls、ToolboxStorage、ZipUp、FoldTowel、PackBag）±BRA；单臂任务不能掉。

#### 3.5.4 为什么不做完整 3D SLAM

- 桌面固定场景、短 episode（6–38 s）；完整 SLAM/NeRF/Gaussian 过重。
- 对象槽位足够表达“物体在哪、是否被遮挡、谁在操作”；计算/内存有界。
- 槽位可解释、可调试、可安全回退；适合比赛。

### 3.6 E 层：VGE

#### 3.6.1 不确定性

```text
u_t = w1 * u_reproj + w2 * u_slot + w3 * u_pred + w4 * u_contact
```

- `u_reproj`：头部双目/腕部特征重投影不一致；可用 PMT 的 ray 一致性/循环对应。
- `u_slot`：槽位突然消失/漂移/匹配代价高。
- `u_pred`：若保留轻量未来头，预测下一帧特征/槽位与观测的误差。
- `u_contact`：接触相位与视觉接触不一致（接 FACT-VLA）。

#### 3.6.2 决策

| 不确定性 | 行为 |
|---|---|
| 低 | 正常执行 chunk 的可靠前缀 |
| 中 | 减速、缩短 chunk、请求更高分辨率腕部/历史帧 |
| 高 | 暂停、重观察、回退安全端点/恢复策略 |

- 阈值在 held-out 标定组 + 扰动集上校准；目标：失败率下降，误停 <5%。
- 延迟只在高不确定时增加；不要把 VGE 做成每步都跑的大模型。
- 记录每次门控的触发原因，便于赛后分析。

### 3.7 接口工程

#### 3.7.1 多速率观测

示例配置（需按实际延迟调）：

```json
{
  "obs_delta_indices": {
    "observation.images.cam_left_high": [-4, -2, 0],
    "observation.images.cam_right_high": [-4, -2, 0],
    "observation.images.cam_left_wrist": [0],
    "observation.images.cam_right_wrist": [0],
    "observation.state.left_arm": [0],
    "observation.state.right_arm": [0],
    "observation.state.left_ee_pose_gripper_base": [0],
    "observation.state.right_ee_pose_gripper_base": [0],
    "observation.state.left_gripper": [0],
    "observation.state.right_gripper": [0],
    "observation.state.lower_body": [0],
    "observation.language": [0]
  },
  "image_resize": {
    "observation.images.cam_left_high": [240, 320],
    "observation.images.cam_right_high": [240, 320]
  },
  "action_chunk_size": 30
}
```

- 头部：低分辨率 + 历史，供几何/对象记忆；腕部：高分辨率 + 当前，供接触。
- `image_resize` 后内参同步缩放：`K' = diag(sx, sy, 1) K`；否则 PMT/MGD 几何错。
- 历史用首帧填充；不要让 padding 被当成真实运动。

#### 3.7.2 N 端口并发

```text
Client ports 8765..8765+N-1
        │
        ▼
WebSocket servers (N) ──► Scheduler (batch window, timeout)
        │                         │
        │                         ▼
        │                 Shared GPU backend (one 6B model)
        │                         │
        └────────────► Per-port state: history, slots, phase, VGE, token
```

- 每端口独立 `PortState`；`reset` 只清该端口；不允许全局可变状态。
- 调度器小批量合并请求，设最大等待窗口（如 5–10 ms）；p99 延迟预算。
- 模型副本：6B 在单 GPU 上通常只能放一份；N 端口共享后端，靠状态隔离/调度，而不是 N 份模型。
- 线程安全：锁/队列；避免 Python GIL 下的长阻塞；推理放独立进程/线程池。
- 异常：端口断开/超时/非法动作 → 该端口安全回退，不影响其他端口。

### 3.8 与 FACT-VLA 的整合

| 第 10 轮模块 | 第 11 轮处理 |
|---|---|
| FACTOR（接触相位弱监督） | 保留；作为 VGE 的 `u_contact` 与 BRA 的相位输入 |
| CPT（接触相位训练） | 保留；在 TFC-ER 的每个家族内继续用 |
| CAC（chunk 边界/柔顺） | 保留；与 VGE 的 chunk 前缀/减速结合 |
| EGP（证据门控 probe） | 更新：单任务调试可 probe；计分提交全 32；榜单 Coming Soon 不用种子当 SOTA |
| DGS-32C | 扩展为 DGS-32V：加标定组、视角缺失、遮挡、对象恒存、遗忘切片 |
| 新增 | MGD/PMT、TFC-ER、OVM/BRA、VGE |

一句话：**FACT-VLA 管“怎么碰”，CORE-VLA 管“东西在哪、还在不在、以前会的还记不记得”。**

## 4. 实验设计

### 4.1 假设

- H1：训练期双目几何（MGD）能提升 held-out 标定组/视角扰动下的成功率，推理延迟不增。
- H2：任务家族顺序 + ER 在同算力下优于 joint 32-task，或至少遗忘更少。
- H3：对象槽位记忆能提升遮挡/移出视野/干扰物切片的成功率。
- H4：BRA 能提升双手任务子集，单臂任务不掉。
- H5：VGE 能降低“自信地做错”的失败率，误停 <5%。
- H6：多速率观测 + N 端口状态隔离能在延迟预算内稳定运行。

| ID | 基线 | 用途 |

| G1 | MGD 是否真的有用？ | B2 vs B3 vs B4，held-out 标定组/视角扰动 | 平均 +2pp，或视角扰动 +5pp；推理延迟不增 | 只保留 PMT 或砍掉 |
| G2 | 持续课程是否优于 joint？ | B4 joint vs B5，同算力，held-out 家族 | 平均 +2pp 或遗忘 −3pp | 保留 joint，只取其他层 |
| G3 | OVM 是否解决遮挡/对象恒存？ | B5 vs B6，遮挡/移出视野/干扰物切片 | +3pp；槽位跟踪误差下降 | 缩到 8 槽位或砍掉 |
| G4 | BRA 是否改善双手任务？ | B5 vs B6，双手任务子集 | 双手子集 +2pp，单臂不掉 | 砍掉或只在双手家族启用 |
| G5 | VGE 是否减少自信错误？ | B6 vs B7，扰动集 + 真机 debug | 失败率下降；误停 <5% | 提高阈值/只保留重观察 |
| G6 | 接口是否扛住 N 端口？ | N 端口并发压测 | p99 在预算内；状态不串 | 减功能/加副本/降分辨率 |
| G7 | 全量是否值得提交？ | 32 任务 × 10 trials 配对 | +3pp 现实，+5pp 冲刺 | 提交安全版 |

### 4.4 消融

- MGD：`L_depth`、`L_corr`、`L_act` 三项逐一去掉；训练期/推理期对比。
- PMT：固定外参 vs 学习腕-手外参；有无 ray embedding；view dropout 比例。
- TFC-ER：家族顺序 2–3 种；replay 0/1/2/5%；replay 分层 vs 均匀；LoRA rank。
- OVM：槽位数 8/16/32；TTL；有无原型库；自监督 vs 伪标签。
- BRA：角色集合大小；弱标签 vs 学习；只在双手家族启用。
- VGE：不确定性来源组合；阈值；减速/重观察/回退策略。
- 接口：单速率 vs 多速率；分辨率；chunk 长度；N=1/2/4/8。

### 4.5 指标

- 主：任务等权成功率（与官方一致）。
- 次：step score、平均完成时间、超时率、动作 jerk/可变性、延迟 p50/p99。
- 切片：标定组、任务家族、接触相位、语言复述、视角缺失、遮挡、对象恒存、旧任务遗忘。
- 连续学习：平均成功率、BWT、FWT、per-family 曲线。
- 安全：高不确定触发率、误停率、恢复成功率、异常动作限幅触发。

### 4.6 统计设计

- 32×10 = 320 trials；p=0.5 时 SE ≈ 2.56pp。
- 主结论用**配对**：同一任务/同一 trial 顺序/同一初始条件；报告 bootstrap 95% CI。
- 离线验证用 GroupKFold by calibration group；不要按帧随机切。
- 真机 debug 用单任务调试，每任务至少 10–20 trials；只作方向性判断，不替代全量。
- 预注册主指标：成功率；+3pp 为现实目标，+5pp 为冲刺；不追 +2pp 噪声。

### 4.8 执行顺序

1. **G0**：单任务调试验证相机/API/立体对；同时跑数据统计与标定组切分。
2. **B0/B1**：joint 基线 + 四路 concat；确认数据/训练/提交链路。
3. **B2/B3/B4**：PMT/MGD 消融；先小规模（8–12 任务）验证，再全量。
4. **B5**：joint vs TFC-ER；只保留赢家。
5. **B6/B7**：OVM/BRA/VGE；按切片决定是否启用。
6. **G6**：N 端口压测；修状态隔离/延迟。
7. **G7**：单任务 debug → 全量提交；安全版优先。

| # | 创新点 | 动机 | 与现有方案差异 | 技术可行性 | 所需资源 | 落地步骤 | 风险 | 决策 |
|---|---|---|---|---|---|---|---|---|
| 1 | **MGD：训练期头部双目几何教师** | API 无深度；多视角几何是 <30% 的短板；头部双目天然动作等价 | 头部方案多为 concat/场景级深度；MGD 用双目深度+对应+跨视角动作一致，推理零 FLOPs | 高：官方双目已 rectified；SGBM/轻量匹配可做教师 | 811 GB 数据；8×A100 1–2 周；无外部数据 | 深度/对应预计算 → 加轻量头 → 训练 → 移除头 → 视角扰动评测 | 透明物体失败；API 双目未验证；标定漂移 | **主押注** |
| 2 | **PMT：位姿感知多视角 token** | 腕部相机随臂移动；普通 2D 位置编码不知道相机在哪 | 多数 VLA 不做相机位姿注入；PMT 用 Plücker ray + 可学习腕-手外参 | 高：EE 位姿可用；外参可学习；无额外传感器 | 轻量；4×A100 | 加 ray/view embedding → view dropout → 消融 | 外参不可观；坐标系不一致 | **主押注** |

| 4 | **OVM：有界对象槽位记忆** | 遮挡/移出视野/对象身份是泛化轴；头部方案无持久对象记忆 | 不做 SLAM/NeRF；16–32 槽位 + 原型库 + TTL；无梯度 | 中高：自监督 slot attention；轻量头 | 4×A100 1–2 周；槽位内存小 | 槽位头 → 跟踪 → 注入动作专家 → 遮挡切片 | 透明/可变形；漂移；延迟 | **差异化层（门控）** |
| 5 | **BRA：双手角色 token** | 人形双臂任务有交接/稳定/协同；对称动作专家不够 | 显式角色（lead/stabilize/idle）+ 跨臂一致性；弱标签 | 中高：EE/夹爪/相位可弱标注 | 轻量；4×A100 | 角色头 → 条件化 → 双手子集评测 | 角色歧义；单臂过拟合 | **差异化层（门控）** |
| 6 | **VGE：视角证据门控执行** | 模型会“自信地做错”；需要运行时不确定性 | 用多视角重投影+槽位漂移+时序误差，而不是 ensemble | 高：廉价信号；规则简单 | 低；CPU/GPU 都行 | 校准阈值 → 减速/重观察/回退 → 扰动集评测 | 误停；阈值难校准 | **运行时必备** |
| 7 | **多速率观测 + N 端口状态隔离** | API v2 支持 obs_delta_indices/image_resize；N 机器人并发 | 多数方案固定全视图同速率；不处理端口状态 | 高：接口原生支持 | 低；工程 1–2 周 | 压测 → 配置 → 状态隔离 → p99 优化 | 缩放内参错；并发串状态 | **必须做** |
| 8 | **DGS-32V：标定组/视角/遮挡/遗忘切片** | 平均成功率掩盖失败；10 组标定 | 在 DGS-32C 上加几何/记忆/CL 切片 | 高：离线可算 | 低 | 切分 → 评测 → 报告 | 样本小；标注少 | **必须做** |
| 9 | **MVFC：多视角未来一致性（可选 hybrid）** | DreamZero 证明 dynamics 有用但太重；轻量未来头可蒸馏 | 不生成视频；预测下一帧特征/槽位，训练后移除 | 中：需要额外头/训练 | 4×A100 1–2 周 | 加未来头 → 对比损失 → 移除 → 消融 | 预测平凡；无增益 | **观察/P2** |
| 10 | **测试时视角校准/原型自适应（可选）** | 新相机/背景偏移；但不想 TTT/RL | 只做 per-episode 归一化/原型 EMA，不改策略权重 | 中：规则/可信度需确认 | 低 | 校准 → 原型 EMA → 门控 | 规则风险；漂移 | **观察/P3** |

**剪枝说明**：

- **完整 world model / DreamZero 复刻**：14B、7 Hz、视频生成；比赛延迟/单模型/安全不划算。只保留 MVFC 这种训练期轻量头作为可选。
- **在线 TTT / RL**：无标签、无 reward、真机试错贵；规则与可信度风险[S27]。
- **触觉/力/力矩**：API 没有；第 10 轮已改接触相位。
- **完整 3D SLAM / NeRF / Gaussian**：桌面短 episode，过重；OVM 足够。
- **盲目多视角 concat**：共置头部相机会干扰；腕部是移动相机；必须 PMT/几何。
- **复杂 CL（EWC/adapter 路由）**：先 ER+LoRA；复杂方法在 32 任务上未必划算。
- **多模型 ensemble**：违反通才单模型；N 端口并发扛不住。
- **pivot/腰部扩展工作空间（主路径）**：大多数任务 pivot 静态，lower_body 是平衡控制器；只对 OrganizeTools/StorePaddle/FoldTowel/PaperCupStacking 做可选开关，不编造通用自由度。

## 6. 风险、合规与开关

| 风险 | 影响 | 缓解 | 开关 |
|---|---|---|---|
| API 头部相机≠数据集双目 | MGD 失效 | 单任务调试 G0；极线/视差检查 | 退回单目深度/2D 对应 |
| 腕部无外参 | PMT 几何错 | 学习腕-手外参；初始化 CAD；消融 | 腕部只做外观 token，不做几何 |
| 透明/反光/可变形 | 深度/槽位失败 | 置信度过滤；对应/外观；TTL | 降权/关闭 MGD 深度项 |
| 标定漂移 | 跨组泛化差 | GroupKFold；PMT 位姿；扰动训练 | 按标定组重校准 |
| TFC-ER 不如 joint | 白做 | 同算力 A/B；保留 joint 分支 | 关闭 TFC-ER |
| OVM 漂移/延迟 | 错误记忆 | TTL；不确定性；轻量头；8 槽位 | 关闭 OVM |
| VGE 误停 | step score 下降 | 校准；误停<5%；只在高不确定时触发 | 降低门控强度 |
| N 端口状态串 | 评测失败 | 每端口状态；线程安全；压测 | 减功能/加副本 |
| 外部数据/伪标签违规 | 取消资格 | 默认 OFF；只用官方数据；训练期伪标签需确认 | 关闭外部标签 |
| 单模型违规 | 取消资格 | 所有头共享 checkpoint；不部署外部在线模型 | 移除外部依赖 |
| 种子榜单误读 | 可信度受损 | 明确“占位数据”；不声明 SOTA | 只引用官方当前页 |

**合规原则**：

- 一个 checkpoint 覆盖 32 任务；MGD/OVM/BRA/VGE 都是同一模型的头/运行时，不是多模型 ensemble。
- 默认不使用外部数据；MGD 教师来自官方双目；若用 SAM2/GroundingDINO 伪标签，只在训练期且需规则确认。
- 不把种子 JSON 当当前榜单；不声称未复现的 +20pp。
- 真机安全：VGE 高不确定回退安全端点；动作限幅/超时；N 端口隔离。

## 9. 一句话押注

**用头部双目做训练期几何教师（MGD），用位姿感知的多视角 token（PMT）把腕部移动相机讲清楚，按任务家族做持续训练 + 2% 分层 replay（TFC-ER），再加有界对象槽位/双手角色（OVM/BRA）与视角证据门控（VGE）——在同一个 WLA-1.0-Base checkpoint 上同时解决多视角几何、任务干扰和对象恒存，这是本轮最值得押注的线。**
