# 第 70 轮（承接第 69 轮「FLUID-RAS」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「隐私保护」×「状态估计」）

> R69 把不确定性拆成 aleatoric / epistemic，并让系统学会「向谁求证、还能问什么」。但它从未问过一个更基本的问题：**为了知道自己在哪、要做什么，我必须把多少关于他人的信息交出去？** 状态估计是整条具身闭环的**信息漏斗**——原始像素、麦克风波形、力觉、家庭布局、人脸与声纹，先在传感器侧汇聚，再被压缩成状态、动作、问句、证书，最后流向前景策略、冻结 LLM、云端世界模型、审计缓冲与操作员。R66–R69 一直在给这个漏斗加「可信度」的阀门，却没有给漏斗**装侧壁**：每一个下游消费者拿到的信息粒度，从来不是被显式设计、认证和审计的。
>
> 更糟的是，R69 刚刚给系统装上了「会问的嘴」——注视、探针、问句。**交互本身就是一条新的、高带宽的泄漏通道**：注视方向暴露它在意什么，问句时序暴露人的作息，LLM 的软提示可能被反演回视觉特征。R69 用 VoI 决定「值不值得问」，却完全没有「问了会不会说漏」这一项。
>
> 本轮两个灵感正好补上两块缺失：
> - **状态估计**给出一个可分解的对象——把潜状态拆成「任务充分统计量」与「敏感冗余」，隐私不再是对整个状态加噪声，而是**只估计、只披露任务真正需要的那一维**；
> - **隐私保护**给出一种可证明、可复合、可审计的**信息流纪律**——差分隐私、最小披露、按主体预算、跨轮复合；它天然是「流」的约束，而不是「值」的约束。
>
> 核心命题：**把「可信」从「我的估计准不准」扩展为「我的估计允许谁、以多细的粒度、在多长的时间上知道什么」；任务充分维度上的估计与 R69 完全一致，敏感维度默认不出设备；只有在任务维度与敏感维度不可分（隐私税 > 0）时，才显式付出精度或交互代价；预算耗尽/被攻击/标定吸收噪声时，退化为隐私优先的保守包络。** 命名 **VEIL-RAS**（Veiled Estimation with Information Least-privilege）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证、还能问什么」，R70 问「**为了知道，我最多可以说出多少**」——隐私不是给状态估计戴上的口罩，而是它的**信息披露预算**。

## 0. 直觉与动机

**灵感 1（状态估计是漏斗，隐私是漏斗的侧壁）**
直觉：一个移动机器人要抓杯子，真正需要的是「杯口相对位姿 + 障碍距离 + 自身速度」这几个数；它**不需要**主人的脸、声纹、家里几口人、卧室布局。但现代具身栈把这些原始信号一路往上送：视觉 token 进 VLA、音频进 LLM、点云进云端 WM、残差进审计日志。泄漏不是发生在「状态估计器输出」那一个点，而是发生在**每一层向每个消费者交付信息的那条边**上。所以隐私的正确对象不是标量 U，而是**披露程序**：谁（consumer）、拿什么投影（view）、为什么目的（purpose）、消耗多少预算（budget）。这把 R68 的「标量风险」、R69 的「标量不确定性」升级为**有类型的信息流**。

**灵感 2（任务充分统计量 → 免费隐私）**
直觉：如果任务损失只通过 s_task 依赖潜状态 z，而 s_task 与敏感属性 n_sens 独立（例如「杯口几何」与「主人身份」在统计上几乎正交），那么**只发布 s_task 就几乎不泄漏 n_sens**——这是「免费隐私」（free privacy）。隐私的第一性原理不是「加噪」，而是**只估计该估计的**：先做任务充分解耦（TSD），再谈差分隐私。把隐私默认当成「给所有数据加高斯噪声」是工程上的懒惰，它既伤精度又给不出「其实根本不必发布」这个更强的保证。

**灵感 3（相关维度 → 隐私税，且可下界）**
直觉：并非总能免费。若 s_task 与 n_sens 相关（ρ_ps = I(s_task; n_sens) > 0，例如「个性化助老」必须知道是谁才能决定扶不扶、而身份又是敏感属性），则任何对 n_sens 做 ε-DP 的发布都必然扭曲 s_task。这不是调参问题，而是信息论下界：**隐私税 ∝ ρ_ps**。于是系统第一次可以诚实地回答「这条隐私保护到底让任务变差多少」，而不是拍脑袋加噪声。更重要的是，它把隐私从「合规开关」变成**可优化的控制变量**——在 PUS 前沿上自适应选择披露粒度。

**灵感 4（交互是新的泄漏通道，且复合）**
直觉：R69 的「看—问—触」每一个都是信息动作，但**信息动作是双向的**：它在获取信息的同时**发出了信息**。注视方向泄漏它认为哪里重要；探针时序泄漏人的活动节律；问句的软提示可被反演回感知特征；同一个问题问十次，每次都「ε-安全」，合起来却足以识别一个人。**单轮安全 ≠ 全天安全**，因为隐私损失是**可复合的**（composition），而 R69 的证书是逐轮的、会归零的。R70 必须把「预算」做成全局账本，且永不重置。

**灵感 5（对偶风险 → 标定会吸收隐私噪声）**
直觉：这是本轮与 R68/R69 血脉相连的一刀。R68 证明了缓变故障会被标定层「解释掉」（r_res≈0）；R69 证明了行为似然是标定不可吸收的第二意见。现在把 DP 噪声注入估计器，**标定层会把它当成传感器漂移学进去**：残差被噪声抬高，COF 就把漂移估计得更大，随后在真漂移到来时**低估**它——系统在「已经加了隐私噪声」和「已经校准过噪声」之间反复横跳，最终要么悄悄撤销了隐私保护（把噪声当漂移减掉），要么过度自信。**隐私噪声必须被打上标签，禁止被标定吸收**，否则 R70 会变成一个「证书合法、实际裸奔」的系统。

**灵感 6（隐私属于场景里的人，不属于机器人；且多主体）**
直觉：状态估计的场景里有人。隐私的主体是被观测者（主人、访客、路人、护工），不是机器人。一个从未同意的路人，对身份/人脸/声纹的预算是 ε=0；「安全攸关」可以有紧急豁免，但必须最小化、留痕、事后可审计。把隐私预算做成**按主体记账**，是从「机器人自己的合规」升级为「对第三方的权利契约」——这也是具身系统真正会被告上法庭的地方。

## 1. 形式化定义（增量：定义 310–326）

**定义 310（VEIL-RAS 总览）** VEIL-RAS = (TSD, PSE, MPD, IPA, PCC, PSG, PAC, RAS-WM‡)。四不变式：
(i) **实时流零学习写操作**（继承 R68 定义 276-i）；
(ii) **本地优先**：原始观测、原始特征、原始问句嵌入永不出可信边缘；出设备的只能是经 MPD 投影、且满足预算的任务充分统计量；
(iii) **隐私预算硬约束**：存在全局 (ε_tot, δ_tot) 与按主体预算 ε_j；预算只减不增、跨轮复合、证书不得重置；
(iv) **严格包含与安全单调**：当所有 ε → ∞（关闭隐私）时，VEIL 与 R69 逐指令相同；当预算耗尽/同意撤回/检测到吸收或攻击时，退化为隐私优先保守包络，其安全风险不高于 R69 的 λ_floor 兜底。

**定义 311（任务充分解耦 TSD）** 潜状态分解为 z = (s_task, s_aux, n_sens)：s_task 是任务损失的**最小充分统计量**（I(s_task; task) = I(z; task)），n_sens 为敏感属性（身份、人脸嵌入、声纹、健康、关系、精确家庭布局），s_aux 为上下文。定义**充分性缺口** Δ_suf = I(n_sens; task | s_task)（理想为 0）与**隐私耦合** ρ_ps = I(s_task; n_sens)（决定隐私税）。TSD 的输出只允许 s_task 与受限的 s_aux 离开本地。

**定义 312（预算化状态估计器 PSE）** 量测模型 y_t = h(z_t) + v_t；PSE 在本地做递推滤波，并对**发布量**施加 (ε_t, δ_t)-局部差分隐私：r_t = q_t(y_{≤t}) + η_t，η_t 按隐私会计分配的高斯/拉普拉斯噪声，满足 clip 后敏感度有界。发布量 r_t 才进入 R69 的 MTM/流策略；原始 y_t 不进入任何跨设备路径。**隐私-精度下界**：对 d 维状态，任意 (ε,δ)-DP 递推估计满足 tr(P_t) ≥ tr(P_t^CRLB) + c·d·C²/ε²（高隐私区误差以 1/ε² 增长），该下界是后文引理 20 的紧化目标。

**定义 313（最小披露数据流 MPD）** 消费者集合 𝒞 = {planner, llm_decoder, cloud_wm, audit, operator, certificate}。每个消费者 c 只能获得一个**投影视图** Φ_c(z) = (s_task, π_c(s_aux, n_sens))，其中 π_c ∈ {redact, coarsen, marginalize, drop} 由目的绑定的策略格（purpose lattice）决定；要求 I(Φ_c(z); n_sens) ≤ ε_c，且**未声明的用途默认拒绝**（least privilege）。特别地：LLM 解码器只拿符号化问句槽与任务几何，不拿原始像素/音频；云端 WM 只拿粗粒度 s_task；审计只拿 DP 摘要。任何视图发布都写入哈希链账本。

**定义 314（交互隐私泄漏与隐私修正 VoI IPA）** 对信息动作 g，其泄漏 L(g) = I(n_sens ; y_g | g, o) + L_side(g)，其中 L_side 为注视/时序/停顿的侧信道泄漏。R69 的 VoI 选择升级为
g* = argmax_g [ VoI(g) − c(g) − λ_p · L(g) ]，s.t. risk(g) ≤ ε_int、预算未超、且每个受影响主体的 purpose 允许。
**敏感推断纪律**：任何关于敏感属性的结论不得由单次交互单独定案；需显式同意 + k 个正交证据 + 目的绑定，否则该结论只作内部先验、不对外披露。

**定义 315（隐私-标定耦合 PCC，反吸收）** DP 噪声 η 在估计器中被**打标**并携带已知方差 σ_DP²(t)。标定层（COF）必须使用噪声知情残差 b_t = y_t − h(ẑ_t) − η̂_t，其中 η̂_t 为噪声代理；**禁止**把 η 学成漂移。反吸收判据：若估计漂移与已知噪声调度 η_sched 的相关性 corr(ĉ_drift, η_sched) > τ_abs，则判定为「隐私噪声被标定吸收」，置 absorption_flag，走定义 319 兜底。这是 R68 引理 13、R69 引理 17 在隐私侧的镜像：**能被标定吸收的隐私，等于没有隐私**。

**定义 316（按主体隐私治理 PSG）** 每个被观测者 j 持有策略 (ε_j, δ_j, purpose_set, consent_state, retention)。默认：路人身份/人脸/声纹 ε_j = 0；任务攸关信息可走**紧急豁免**（vital interest），但必须最小化、限时保留、留痕、可事后审计。一个观测/交互若涉及主体 j，则消耗 j 的预算，不消耗机器人的预算；同意可随时撤回，撤回后进入保留期删除流程。

**定义 317（隐私会计与复合 PAC）** T 轮、M 个模块的总隐私损失按 Rényi DP / moments accountant 复合：
ε_tot(δ) = min_{α>1} [ Σ_m ε_{α,m} + log(1/δ)/(α−1) ]。
逐轮证书不得归零；J_VEIL 携带累积预算与哈希链账本；账本只追加、可验证、不可篡改。**单轮 ε_single 从不是保证，只有复合 ε_tot 是。**

**定义 318（隐私风险证书 J_VEIL）** J_VEIL = (J_FLUID, ε_tot, δ_tot, {ε_j}, Δ_suf, ρ_ps, L_max, absorption_flag, disclosure_log_hash, veil_ver)。Valid ⇔ Valid(J_FLUID) ∧ ε_tot ≤ ε_budget ∧ 所有主体预算满足 ∧ Δ_suf ≤ τ_suf ∧ 未检测到吸收 ∧ 每个视图均有目的绑定与账本记录。

**定义 319（隐私优先保守包络 PFF）** 当预算耗尽、同意撤回、吸收检测、攻击告警或证书失效时，进入 PFF：原始数据绝对不出设备；状态估计退化为更严 DP 或确定性安全包络（只保留碰撞距离等**非敏感充分量**）；R69 的敏感问句禁用；必要时以**隐私交互**请求同意，但请求本身限频、留痕、计入预算。PFF 的风险上限为 R69 最保守兜底 + ε_safe，安全侧不退让。

**定义 320（威胁模型 ℰ_VEIL）** ℰ_VEIL = ℰ_FLUID × ℰ_privacy，其中 ℰ_privacy = {反演/重建（人脸、户型）, 成员推断, 属性推断, 交互时序/注视侧信道, PSE 模型抽取, 消费者串谋, 账本篡改, 重复查询抵消 DP 噪声}。特别包含**复合攻击**：单个问题都 ε-安全，多次组合即可识别个体。

**定义 321（参与式隐私审计 VQAuditor-P）** 审计对象新增：视图是否越权、目的绑定是否真实、是否发生单源敏感推断、标定是否吸收了隐私噪声、证书预算是否与账本一致。审计器周期性用**带 DP 的重放红队**（反演攻击）度量实际泄漏 L_emp，并与理论下界对比；结论回灌 AuditBuf，成为下一轮 IPA 的泄漏先验与 MPD 的视图收缩信号。

**定义 322（隐私-效用-安全前沿 PUS）** 定义效用 U（任务成功率/估计精度）、隐私 P = −ε_tot、安全 S（违规概率）。可行域由 (Δ_suf, ρ_ps, 交互预算) 决定；当 Δ_suf = ρ_ps = 0 时为**免费隐私区**（隐私不损效用，定义 311、引理 19）；当 ρ_ps > 0 时存在不可避免的权衡（引理 20）。控制器在前沿上选点，而不是在固定约束下硬做。

**定义 323（自适应披露粒度）** 每轮选择披露档位 d ∈ {raw_local, task_suff, coarsened, symbol_only, none}，在满足安全与预算下最大化 U(d) − λ_p·ε(d)。隐私由此与 R68 的 λ、R69 的 g 并列，成为**第三个自适应控制变量**：系统不仅决定「走多快、问不问」，还决定「**说多细**」。

**定义 324（重建抵抗度）** 泄漏的经验度量 L_emp = max_{A∈𝒜} Acc(A(Φ_c(z)) → n_sens)，𝒜 为红队攻击族（重建、成员、属性推断）。要求 L_emp ≤ L_bound(ε_tot, δ_tot) + ε_est，其中 L_bound 由 DP 后处理定理给出；若 L_emp 显著超界，说明存在 DP 之外的结构性泄漏（如 TSD 识别错误），证书必须作废。

**定义 325（符号接地瓶颈 SGB）** R69 的问句 g_ask 经冻结 LLM 解码前，必须通过一个**符号瓶颈**：将 g_ask 量化到封闭的任务谓词词表（如 `near(object)`、`side(left/right)`、`may_touch(force≤f)`），并对软提示施加 DP 后再解码；禁止把连续感知特征直接喂给 LLM。给出可逆性界：从符号槽反演原始特征的互信息 ≤ ε_sym，从而堵住「问句 → 视觉特征」的反演通道。

**定义 326（严格包含契约）** 关闭隐私（ε ≡ ∞、MPD 直通、PAC 不计账）时，VEIL 的每一个控制指令与 R69 相同；开启隐私时，PFF 的安全风险 ≤ R69 最保守兜底。因此 R69 是 VEIL 在「无隐私约束」边界上的退化，VEIL 是 R69 的**严格泛化**而非并列替代——这是本轮不允许退让的理论姿态，否则每加一层隐私就多一个独立黑箱。

## 2. 关键算法骨架

```python
# IP-264 TSD：任务充分解耦（复用 R69 MTM trunk，零重复训练；敏感头只在本地做红队检查）
class TaskSufficientSplitter:
    def __init__(self, trunk, task_head, aux_head, sens_probe):
        self.trunk, self.task = trunk, task_head     # z -> s_task（最小充分）
        self.aux, self.sens  = aux_head, sens_probe  # 仅本地，绝不外发

    def split(self, o_t):
        z = self.trunk(o_t)
        return self.task(z), self.aux(z), self.sens(z)   # 只允许 s_task/s_aux 外流

# IP-265 PSE：本地 DP 递推估计（clip + 校准噪声 + 预算记账）
class DPStateEstimator:
    def __init__(self, dyn, clip_C, sigma_sched, accountant):
        self.dyn, self.C, self.sched, self.acct = dyn, clip_C, sigma_sched, accountant

    def step(self, y_t):
        r_t = clip(y_t, self.C) + self.sched.noise(t=self.acct.t)  # 局部 DP
        self.x = self.dyn.update(self.dyn.predict(self.x), r_t)     # 发布量才进下游
        self.acct.spend(self.sched.eps(t=self.acct.t))
        return self.x, r_t, self.sched.last_noise()                # 噪声打标给 PCC

# IP-266 MPD：最小披露（目的绑定 + 投影 + 账本）
VIEWS = {"planner":     ["s_task"],
         "llm_decoder": ["g_ask_symbols", "s_task_slots"],       # 无原始像素/音频
         "cloud_wm":    ["s_task_coarse"],                       # 默认更粗，无同意则空
         "audit":       ["dp_summary"], "operator": ["s_task"]}
def disclose(x, consumer, subjects, purpose):
    if purpose not in POLICY[consumer].purposes: return None     # 未声明用途拒绝
    view = project(x, VIEWS[consumer])
    view = redact(view, [POLICY[s] for s in subjects])
    assert leakage_bound(view, subjects) <= POLICY[consumer].eps
    LEDGER.append(consumer, hash(view), purpose)
    return view

# IP-267 IPA：隐私修正的交互决策（R69 VoI 加泄漏项）
def choose_interaction(modes, w, o_t, budget, subjects):
    best = None
    for g in info_candidates(modes):                             # 注视/探针/问句
        if not budget.allow(g) or not all(s.allows(g.purpose) for s in subjects): continue
        L = leakage(g, subjects) + side_channel(g)               # 内容 + 时序/注视
        score = (entropy(w) - expected_entropy(w, g, o_t)) - cost(g) - LAM_P * L
        if best is None or score > best.score: best = (g, score)

# IP-274 主闭环（继承 R69，仅在信息流与交互处置处插入 VEIL 层）
```

## 3. 推导

**引理 19（充分即免费）** 若 s_task 是任务的最小充分统计量且 I(s_task; n_sens) = 0，则存在披露机制以 ε = 0（相对 n_sens）发布 s_task，且任务期望风险与发布完整 z 时相同。证明要点：任务损失经 s_task 中介，n_sens 与 s_task 独立 ⇒ 发布 s_task 不提供任何 n_sens 的信息，DP 后处理不增加泄漏；故隐私税为 0。**系**：大量「机器人只需要几何」的场景属于免费隐私区，此时 R70 的全部收益不花任务精度——这也是 TSD 必须先于加噪的原因。

**引理 20（耦合维度的隐私税下界）** 设 ρ_ps = I(s_task; n_sens) > 0，发布机制对 n_sens 满足 (ε,δ)-DP。则任何估计器对 s_task 的极小极大均方误差满足
MMSE ≥ c · exp( (2/d)(h(s_task) − ε) ) 或等价地 ≥ c′·ρ_ps·(1 − e^{−ε})²，
即隐私税随耦合强度与隐私强度增加，且在高隐私区无法通过更多数据消除（只随 d 与熵变化）。**系**：当 ρ_ps 大时，唯一诚实的做法是显式降级任务（定义 323 的粗粒度披露），而不是假装「加一点噪声没影响」。

**引理 21（隐私噪声的反吸收性）** 设 COF 残差含已知 DP 噪声 η_t（方差 σ_DP²）与真漂移 δ_t（方差 σ_d²）。若标定器把 η 当漂移，则漂移估计的渐近偏差 E[ĉ − c] ≥ σ_DP²/(σ_DP² + σ_d²)·|δ|，导致对真漂移的系统性低估；且该偏差与噪声调度的相关性在 T 步内以 O(√T) 增长。故可用 corr(ĉ, η_sched) > τ_abs 检出吸收。**系**：**能被打标噪声调的标定层吸收的隐私，等于没有隐私**——与 R68 引理 13、R69 引理 17 同构。

**引理 22（交互泄漏的复合下界）** 若单次信息动作对主体 j 满足 ε_j-DP，T 次自适应的、基于历史回答选择的查询后，有效隐私损失至少按 Rényi 复合增长， adversary 对 n_sens 的识别成功率下界为 1 − e^{−Σ_t ε_j^{(t)}}（近似），且查询可自适应地最大化信息。**系**：R69 的「单次交互不单独定案」在隐私侧必须升级为「单次交互不单独消耗信任 + 全局复合会计」；否则一串各自安全的问题就是一次慢速人肉搜索。

**定理 18（VEIL 严格包含 R69）** 在 A99–A103（充分性、DP 后处理、噪声知情标定、主体策略一致）下，对任意状态：开启隐私且预算充足时，VEIL 的任务期望风险 ≤ R69（因为 R69 可视为 d = raw 的特例，VEIL 允许更细的 d，但 MPD 是后处理、不改变可用任务信息）；关闭隐私时逐指令相同；预算耗尽时 PFF 的风险 ≤ R69 最保守兜底 + ε_safe。故 R69 = VEIL 的「ε→∞」边界。

**定理 19（PUS 三难前沿）** 当 ρ_ps > 0 时，不存在同时达到「任务风险 ≤ δ_task、泄漏 ≤ ε、且交互消歧预算不受限」的策略；三者满足
Φ(δ_task, ε, B_int) ≥ Ω(ρ_ps)，
即耦合维度的信息无法被同时「用足」和「藏好」。前沿的拐点由 Δ_suf、ρ_ps 与主体同意率共同决定。**系**：R69 的「resolution bonus」在隐私下是有条件的：能消解的 epistemic 若与敏感属性耦合，其交互可能先耗尽预算。

**定理 20（认证无静默降级）** 在全局 PAC、PCC 反吸收与按主体 PSG 同时在线时，系统在 T 轮内要么输出合法 J_VEIL（真实满足 (ε_tot, δ_tot)-DP 与主体预算），要么进入 PFF；不存在「证书合法但实际泄漏超界」的静默路径（在吸收检测的假阴性率 ≤ α 与账本不可篡改的前提下，静默降级概率 ≤ α + negl(κ)）。这把 R68「标定吸收导致隐形故障」的教训，升级为隐私侧的**可认证不隐形**。

## 6. 本轮最大风险

**一句话**：VEIL-RAS 的全部保证押在「敏感子空间 n_sens 已被正确识别、且任务通道与它真的可分离」这一前提上——**若 TSD 把身份/情绪/户型悄悄编码进了 s_task（或噪声被标定层当成漂移吸收、或一串各自 ε-安全的交互被自适应地复合成一次识别），系统就会拿着一张合法的 J_VEIL 证书，泄露它发誓要保护的东西**——**合规的泄漏，比裸奔更危险**。

**次级风险与缓解**：
1. **标定吸收隐私噪声**（悄悄撤销保护）→ PCC 噪声打标 + 反吸收相关性检验 + 引理 21 + E304；一旦越界立即 PFF；
2. **复合/自适应查询攻击** → 全局 PAC + 主体预算 + 引理 22 + 单源敏感推断禁令 + E307/E313；
3. **结构性泄漏绕过 DP**（s_task 间接编码身份）→ TSD 红队探针 + L_emp 实测 + 定义 324 超界即废证 + E308；
4. **LLM/问句反演** → 符号瓶颈 SGB + 软提示 DP + E309；
5. **多主体权利冲突**（安全需要 vs 路人 ε=0）→ PSG 紧急豁免 + 最小化留痕 + 事后审计，绝不以「安全」为名无限扩权。

**定义 316（PSG）** 每主体 (ε_j,δ_j,purpose,consent,retention)；路人身份/人脸/声纹 ε_j=0；紧急豁免最小化、限时、留痕、可审计；同意可撤回并进入删除流程。

**定义 317–318（PAC 与 J_VEIL）** RDP 复合出 ε_tot；账本只追加不可篡改；J_VEIL 并入累积预算、主体向量、Δ_suf、ρ_ps、L_max、吸收标志；Valid 需 R69 证书 ∧ 预算 ∧ 主体 ∧ 无吸收。

**定义 319–321（PFF / 威胁 / 审计）** PFF：预算耗尽/撤回/吸收/攻击时原始数据不出设备、只保留非敏感充分量、禁用敏感问句、可请求隐私同意（限频留痕），风险 ≤ R69 兜底+ε_safe。ℰ_VEIL=ℰ_FLUID×ℰ_privacy（反演/成员/属性/侧信道/模型抽取/串谋/账本/重复查询抵消）。VQAuditor-P 用带 DP 的重放红队实测 L_emp 并回灌 AuditBuf。

**定义 322–323（PUS 与自适应披露）** 效用 U、隐私 P=−ε_tot、安全 S 的前沿；Δ_suf=ρ_ps=0 为免费隐私区，ρ_ps>0 有硬权衡。每轮选披露档位 d，使隐私与 λ、g 并列成为第三个自适应控制变量。

**定义 324–326（重建抵抗 / 符号瓶颈 / 严格包含）** `L_emp ≤ L_bound(ε_tot)+ε_est`，超界废证；g_ask 量化到封闭谓词词表并对软提示 DP 后再交冻结 LLM 解码，反演互信息 ≤ ε_sym；ε∞ 时逐指令等于 R69，开启时 PFF 不弱于 R69 兜底 ⇒ R69 是 VEIL 的退化边界。

## 3. 关键算法伪代码

```python
# IP-264 TSD：任务充分解耦（复用 R69 MTM trunk；敏感头仅本地红队用）
class TaskSufficientSplitter:
    def split(self, o_t):
        z = self.trunk(o_t)
        return self.task(z), self.aux(z), self.sens(z)   # 仅 s_task/s_aux 可外流

# IP-265 PSE：本地 DP 递推估计（clip + 校准噪声 + 记账）
class DPStateEstimator:
    def step(self, y_t):
        r_t = clip(y_t, self.C) + self.sched.noise(self.acct.t)   # 局部 DP
        self.x = self.dyn.update(self.dyn.predict(self.x), r_t)
        self.acct.spend(self.sched.eps(self.acct.t))
        return self.x, r_t, self.sched.last_noise()               # 噪声打标给 PCC

# IP-266 MPD：最小披露（目的绑定 + 投影 + 账本）
def disclose(x, consumer, subjects, purpose):
    if purpose not in POLICY[consumer].purposes: return None      # 未声明用途拒绝
    view = redact(project(x, VIEWS[consumer]), [POLICY[s] for s in subjects])
    assert leakage_bound(view, subjects) <= POLICY[consumer].eps
    LEDGER.append(consumer, hash(view), purpose)
    return view

# IP-267 IPA：隐私修正交互（R69 VoI 加泄漏项）
def choose_interaction(modes, w, o, budget, subjects):
    best = None
    for g in info_candidates(modes):
        if not budget.allow(g) or not all(s.allows(g.purpose) for s in subjects): continue
        score = (entropy(w) - expected_entropy(w, g, o)) - cost(g) \
                - LAM_P * (leakage(g, subjects) + side_channel(g))
        if best is None or score > best.score: best = (g, score)
    return best if best and best.score > 0 else None              # 无利可图 → R69 兜底

# IP-268 PCC：噪声知情标定（禁止吸收 DP 噪声）
def cof_update(belief, y, noise_sched):
    r = y - belief.predict() - noise_sched.expected()
    if corr(r, noise_sched.samples()) > TAU_ABS:
        flag_absorption(); raise PrivacyAbsorptionDetected        # 走 PFF
    return belief.update(r)

# IP-274 主闭环（继承 R69，仅在信息流与交互处置处插入 VEIL 层）
def VEIL_RAS_round(M, o):
    s_task, s_aux, _ = M.tsd.split(o)                    # 0) 本地解耦
    _, r_t, noise = M.pse.step(o); M.pac.spend(M.pse.last_eps)   # 1) 本地 DP 估计
    z = M.mtm.forward(s_task)                            # 2) R69 闭环只在 s_task/r_t 上跑
    K = 1 if M.fmp.mode_head(z) < TAU_MODE else 4
    U_ale, U_epi, modes, _ = M.aud.decompose(M.fmp.sample(r_t, K), z, M.fmp.mode_head)
    a_hat = M.fma.flow_anomaly(M.fmp, M.last_action, r_t, M.o_calibrated)
    slow  = (a_hat > TAU_FMA) and (M.last_r_res < TAU_RES)
    g = (M.ipa.choose_interaction(modes, r_t, M.budget, M.psg.subjects(o))
         if (U_epi > TAU_EPI and not slow) else None)     # 3) 隐私修正交互
    U_epi = M.cia.update_belief(modes, M.cia.execute(g)) if g else U_epi
    M.cof.step(r_t, M.pse.noise_sched)                    # 4) 噪声知情标定（可能置吸收）
    for c in M.consumers: M.mpd.disclose(r_t, c, M.psg.subjects(o), c)   # 5) 最小披露
    if M.pac.exhausted() or M.cof.absorption or M.psg.revoked(o):
        return M.pff(o)                                   # 隐私优先保守包络
    lam = max(M.efs.risk_scale(), lam_floor(U_ale + (U_epi if g is None else 0.0)))
    k   = M.c_ras_wm.certified_prefix(M.ach.propose(), M.wm_preds)
    M.vqa_p.submit_async(g, M.ledger, M.pac.eps_tot)      # 6) 审计 + 证书
    return M.certificate(J_FLUID, eps_tot=M.pac.eps_tot, subjects=M.psg)
```

## 4. 推导

**引理 19（充分即免费）** 若 s_task 是任务最小充分统计量且 `I(s_task; n_sens)=0`，则发布 s_task 对 n_sens 的泄漏为 0，且任务风险与发布完整 z 相同 ⇒ 隐私税 = 0。系：几何类任务处于免费隐私区，R70 的收益不花精度；这就是 TSD 必须先于加噪的原因。

**引理 20（耦合维度的隐私税下界）** 若 `ρ_ps=I(s_task;n_sens)>0`，任何对 n_sens 的 (ε,δ)-DP 发布都使 s_task 的极小极大误差满足 `MMSE ≥ c·exp((2/d)(h(s_task)−ε))`（等价于 ≥ `c′·ρ_ps·(1−e^{−ε})²`）。高隐私区误差无法靠更多数据消除。系：ρ_ps 大时唯一诚实的做法是显式降级任务（粗粒度披露），而非假装「加一点噪声没影响」。

**引理 21（隐私噪声的反吸收性）** 残差含已知 DP 噪声（方差 σ_DP²）与真漂移（方差 σ_d²）；若标定把噪声当漂移，漂移估计偏差 `≥ σ_DP²/(σ_DP²+σ_d²)·|δ|`，且与噪声调度的相关性以 O(√T) 增长 ⇒ `corr(ĉ,η_sched)>τ_abs` 可检。系：能被打标噪声调吸收的隐私等于没有隐私（R68 引理 13 / R69 引理 17 的隐私镜像）。

**引理 22（交互泄漏复合下界）** 单次 ε_j-DP 的自适应查询在 T 次后按 Rényi 复合增长，识别成功率下界约 `1−e^{−Σ_t ε_j^{(t)}}`。系：R69 的「单次不单独定案」必须升级为「全局复合会计」，否则一串各自安全的问题就是一次慢速人肉搜索。

**定理 18（VEIL 严格包含 R69）** A99–A103 下，预算充足时 VEIL 任务风险 ≤ R69（MPD 是后处理，不增加任务可用信息）；关闭隐私时逐指令相同；预算耗尽时 PFF 风险 ≤ R69 最保守兜底+ε_safe。R69 = VEIL 的 ε→∞ 边界。

**定理 19（PUS 三难前沿）** ρ_ps>0 时不存在同时满足「任务风险 ≤ δ_task、泄漏 ≤ ε、交互消歧不受限」的策略，`Φ(δ_task,ε,B_int) ≥ Ω(ρ_ps)`；前沿拐点由 Δ_suf、ρ_ps 与同意率决定。系：R69 的 resolution bonus 在隐私下是有条件的。

**定理 20（认证无静默降级）** 全局 PAC + PCC 反吸收 + 按主体 PSG 同时在线时，T 轮内要么输出合法 J_VEIL（真实满足 ε_tot 与主体预算），要么进入 PFF；在吸收检测假阴性 ≤ α、账本不可篡改下，静默降级概率 ≤ α + negl(κ)。不存在「证书合法但实际泄漏超界」的静默路径。

## 7. 本轮最大风险

**一句话**：VEIL-RAS 的全部保证押在「敏感子空间 n_sens 已被正确识别、且任务通道与它真的可分离」这一前提上——**若 TSD 把身份/情绪/户型悄悄编码进了 s_task（或噪声被标定层当成漂移吸收、或一串各自 ε-安全的交互被自适应复合成一次识别），系统就会拿着一张合法的 J_VEIL 证书，泄露它发誓要保护的东西**——**合规的泄漏，比裸奔更危险**。

**次级风险与缓解**：标定吸收隐私噪声（PCC 噪声打标 + 相关性检验 + 引理 21 + E304，越界即 PFF）；复合/自适应查询攻击（全局 PAC + 主体预算 + 引理 22 + 单源敏感推断禁令 + E307/E313）；结构性泄漏绕过 DP（TSD 红队探针 + L_emp 实测 + 定义 324 超界废证 + E308）；LLM/问句反演（符号瓶颈 SGB + 软提示 DP + E309）；多主体权利冲突（PSG 紧急豁免最小化留痕 + 事后审计，不以「安全」为名无限扩权）。
