# 第 8 轮（新灵感循环第 1 轮；本轮灵感：「云端协同」×「自监督学习」）
> **基线**：第 7 轮 MetricVoiceGauge-OTL-GC-ER（定义 493–529；引理 73–76；实验 E513–E525）。
> 本轮纪律：**云端只给建议、边缘保留否决；自监督只提供不确定性、不直接改写安全约束**。两个灵感合成“信任但验证”的证书协作，任何新组件失效都退回 v7。

## 0. 直觉与动机

**灵感 1（云端协同 → 会诊专家与值班医生）**
直觉：边缘控制器像值班医生，必须在几十毫秒内处理硬实时；云端像会诊专家，见多识广但网络延迟不可控。让云端直接下发动作是危险的；正确做法是让云端下发**有保质期、可验证、只能更保守的“第二意见证书”**。边缘继续跑 v7 本地闭环，只有证书通过来源签名、快照哈希、时效、安全细化四道门，才被采纳为软层建议。

**灵感 2（自监督学习 → 无标签的“正常性”模型）**
直觉：竞赛与部署中大量遥测数据没有标签，但“什么算正常”可以从数据自身学出来：相邻时刻的观测应可互预测，不同模态（视觉、本体、语音）应对同一状态给出一致表征。用时间对比 + 掩码重建训练边缘编码器，得到新颖度 n(o) 与跨视图一致性 a(o)。关键不是让自监督直接做决策，而是让它当**适应调速器的刹车**：当 n 高或 a 低，说明当前分布超出经验，冻结第 7 轮的 OTL/ER 自适应，退回 v7 的保守行为。

**合成直觉（信任但验证）**
第 7 轮最大风险是“过度适应导致退化频率不稳”。本轮把云端和自监督都放在**建议/监督**位置：云端提供长尾语义与世界知识，自监督提供“当前是否可信”的证据；两者都不能放松 M₀/M₁。适应只在“自监督证明不离谱 + 云端证书是安全细化”时发生，形成 **CESSL（Cloud-Edge Self-Supervised Ladder）**。

## 1. 研究问题（轮次升级版）

- **Q1（云边证书接口）**：如何把云端建议编码成可验证、可过期、只能收紧的证书，使其能进入实时闭环，并在断网、高延迟、时钟漂移下无缝退回 v7？
- **Q2（自监督可信度校准）**：如何把无标签的新颖度与跨视图一致性校准成有覆盖率保证的证书，并作为 OTL/ER 的适应门控，而不是新的决策源？
- **Q3（组合退化）**：云端、边缘、自监督三者在冲突或失效时如何按“取更保守者”组合，保证任一环节失效时行为等价于 v7 或 v6，且不产生级联退化？

## 2. 设计原则（在 P7–P9 基础上升级为 P10–P13）

**P10 云端证书契约（Cloud-Edge Certificate Contract, CECC）**
云端只下发结构化证书，不下发原始动作：
```
C = (κ, z_c, u, t_send, TTL, h, π, σ)
Valid(C, o, t) ⇔ Verify_π(σ) ∧ h = H(o) ∧ t − t_send ≤ TTL + δ_clock
```
其中 κ 为类型化建议，z_c 为云端潜表征，u 为置信度，h 为输入快照哈希，π 为模型/提示词来源，σ 为签名。

**P11 安全细化偏序（Safe Refinement Order）**
云端建议必须比边缘本地建议更保守或等价：
```
κ ⪯_safe κ_e ⇔ τ_i(κ) ≥ τ_i(κ_e) (i=0,1) ∧ A(κ) ⊆ A(κ_e) ∧ κ.type ∈ Σ_ι
```
即只允许提高安全层阈值、缩小动作集、保持指令类型合法；不允许放宽 M₀/M₁，也不允许绕过抓取几何检查。

**P12 自监督信任门（Self-Supervised Trust Gate, SSTG）**
用无标签数据训练时序编码器，并以共形分位数校准新颖度 n(o) 与跨视图一致性 a(o)：
```
g(o) = 1[ n(o) ≤ q_{1−α} ∧ a(o) ≥ a_min ]
η_eff = η · g(o),  β_eff = β · g(o)
```
g=0 时冻结 OTL/ER，而不是切换到一个新的学习策略；安全层始终由 v7 的局部闭环兜底。

**P13 边缘否决权（Edge Veto）**
云端辅助语义接地只在本地类型检查与 γ_grasp 都通过时生效；云端不能覆盖硬约束、不能改写抓取几何判据：
```
ι = ι_c  if Accept(C,o,t) ∧ type(ι_c) ∈ Σ_ι ∧ γ_grasp(ι_c)
    ι_e  otherwise
```

## 3. 与基线的接口（如何退化）

- 云端不可用、证书过期或签名失败 ⇒ 不采纳云证书，等价于第 7 轮 v7；
- 自监督编码器或校准器不可用 ⇒ 因缺少可信度证据，同时禁用云证书，退回 v7；
- v7 的 OTL/GCT/ER 再失效 ⇒ 退回第 6 轮 MetricVoiceGauge v6；
- 云端与本地建议冲突 ⇒ 取安全细化偏序下的“更保守者”（阈值逐分量取大、动作集取交），不做平均或投票。

## 4. 预期贡献

1. 一个把云端大模型建议限制为“有期限的安全细化证书”的实时证书框架，避免云端进入硬实时回路；
2. 用自监督新颖度/一致性给在线适应加“刹车”，直接针对第 7 轮过度适应的风险；
3. 云边潜空间蒸馏与证书渡运，兼顾带宽、隐私与边缘断网可用性；
4. E526–E545 覆盖时效、安全、OOD、断网、拜占庭证书与端到端竞赛。

## 5. 本轮最大风险

**一句话**：自监督门控若把“分布内但任务关键”的罕见状态误判为 OOD，会过度冻结适应，使系统在真正需要云/在线适应的长尾场景中反而退化；而云端证书的时钟同步与签名链一旦被破坏，安全细化假设会在陈旧证书上失效。

**定义 530（云端证书 CloudEdgeCertificateContract, CECC）**
云端只产生结构化建议，不产生可直接执行的低层动作：
```
C = (κ, z_c, u, t_send, TTL, h, π, σ)
Valid(C, o, t) ⇔ Verify_π(σ) ∧ h = H(o) ∧ (t − t_send + δ_clock) ≤ TTL
```
其中 κ 是类型化建议（指令类型、软层阈值调整、抓取候选几何），u∈[0,1] 为校准置信度，π 为模型版本/提示词来源，σ 为签名。

**定义 531（安全细化偏序 Safe Refinement Order）**
```
κ ⪯_safe κ_e ⇔ 
    (∀i∈{0,1}: τ_i(κ) ≥ τ_i(κ_e))
  ∧ A(κ) ⊆ A(κ_e)
  ∧ type(κ) ∈ Σ_ι
```
即云端只能提高安全层 M₀/M₁ 的阈值、缩小可执行动作集、保持指令类型合法；软层 M₂/M₃ 可在 [ε_min, ε_max] 内调整，但不得反向放松安全层。

**定义 532（边缘接受谓词 Edge Acceptance）**
```
Accept(C, o, t) ⇔ Valid(C, o, t) ∧ u ≥ u_min ∧ κ ⪯_safe κ_e ∧ a(o) ≥ a_min
```
四个条件分别对应“没被篡改/没错位/够可信/没漂移”。

**定义 533（有界陈旧租约 BoundedStalenessLease, BSL）**
设安全裕度函数 g(s) 关于状态是 L_g-Lipschitz 的，环境最大相对速度上界为 v_max，则
```
Δ_max = ε_m / (L_g · v_max)
Δ(C,t) = t − t_send + δ_clock
```
仅当 Δ(C,t) ≤ min(TTL, Δ_max) 时证书才可被接受。

**定义 534（自监督时序编码器 SelfSupervisedTemporalEncoder, SSTE）**
在无标签遥测窗口上训练边缘编码器 E_θ：
```
L_SSL(θ) = L_InfoNCE(z_t, z_{t+1}; negatives)
         + λ · L_mask(o_t, Dec(z_t))
```
正样本为时间相邻窗口，负样本为同批次其他窗口；不使用任何人工安全/成功标签。

**定义 535（新颖度证书 NoveltyCertificate）**
```
n(o) = 1/2 · [ d(z_t, ẑ_t)/q_pred + min_k ||z_t − μ_k||/q_proto ]
q_{1−α} = Quantile_{1−α}({n(o_i) : o_i ∈ D_cal})
```
q_pred、q_proto 为校准集上的稳健尺度（中位数绝对偏差），μ_k 为表征原型；D_cal 为无标签校准集。

**定义 536（跨视图一致性证书 CrossViewAgreement, CVA）**
```
a(o) = cos(z_e(o), z_c(o)) = <z_e,z_c> / (||z_e||·||z_c||)
a_min = Quantile_α({a(o_i) : o_i ∈ D_cal})
```
云端不可用时，用 IP-357 蒸馏出的教师代理计算 a(o)，但该代理不参与安全层决策。

**定义 537（自监督信任门 SelfSupervisedTrustGate, SSTG）**
```
g(o) = 1[ n(o) ≤ q_{1−α} ∧ a(o) ≥ a_min ]
η_eff = η · g(o),  β_eff = β · g(o)
```
当 g=0 时，OTL 停止更新阈值，ER 退回风险权重，等价于该控制步只运行 v7 的保守配置。

**定义 538（云端辅助语义接地 CloudAssistedSemanticGrounding, CASG）**
```
ι = ι_c   if Accept(C,o,t) ∧ type(ι_c) ∈ Σ_ι ∧ γ_grasp(ι_c)
    ι_e   otherwise
```
云端可提出长尾抓取指令，但本地 GCT 的 γ_grasp 检查拥有最终否决权。

**定义 539（云边潜空间蒸馏 CloudKnowledgeDistillation, CKD）**
```
L_KD(θ) = E_{(o,z_c) ∼ D_acc}[ ||z_e(o) − z_c||² ] + λ_KD · L_SSL(θ)
```
D_acc 只包含被接受证书对应的样本；被拒绝或过期的云端建议不得进入蒸馏，避免把漂移学进边缘。

**定义 540（证书渡运 CertificateFerry）**
```
B_t = { C_k : Accept(C_k, o_k, t_k) ∧ t − t_k ≤ TTL_k },  |B_t| ≤ B_max
```
渡运缓冲只用于自监督校准与蒸馏，绝不作为控制指令重放；过期证书立即清除。

**定义 541（CESSL 闭环标识）**
```
Φ_CESSL = (CECC valid, SSTG calibrated, CASG edge-veto, OTL/ER gated)
Φ_v7    = (no cloud cert, no trust gate, local grounding, OTL/ER on)
Φ_v6    = (no OTL/GCT/ER, fixed τ, risk-only w)
```

**定义 542（组合退化序 Compositional Degradation）**
```
CESSL --cloud✗--> v7
CESSL --ssl✗----> v7
v7    --OTL/GCT/ER✗--> v6
```
云端与 SSL 任一失效都先回到 v7，而不是直接跳 v6；因为 v7 本身已有完整的局部安全闭环。

## 3. 关键算法骨架

```python
from dataclasses import dataclass
import hashlib
import numpy as np


@dataclass(frozen=True)
class CloudCertificate:
    kappa: dict
    z_c: np.ndarray
    u: float
    t_send: float
    ttl: float
    snapshot_hash: str
    provenance: str
    signature: bytes


class SafeRefinementGuard:
    def __init__(self, u_min=0.70, a_min=None, delta_clock=0.005,
                 eps_margin=0.02, L_g=1.5, v_max=1.0):
        self.u_min = u_min
        self.a_min = a_min
        self.delta_clock = delta_clock
        self.delta_max = eps_margin / (L_g * v_max)

    @staticmethod
    def snapshot_hash(obs):
        digest = hashlib.blake2b(repr(obs).encode("utf-8"), digest_size=16)
        return digest.hexdigest()

    def valid(self, cert, obs, now, verify_signature):
        age = now - cert.t_send + self.delta_clock
        return (
            verify_signature(cert.provenance, cert.signature)
            and cert.snapshot_hash == self.snapshot_hash(obs)
            and age <= min(cert.ttl, self.delta_max)
        )

    def refines(self, kappa, edge):
        tau_ok = all(
            kappa["tau"][i] >= edge["tau"][i] for i in (0, 1)
        )
        action_ok = set(kappa["actions"]).issubset(set(edge["actions"]))
        type_ok = kappa["type"] in edge["sigma_iota"]
        return tau_ok and action_ok and type_ok

    def accept(self, cert, obs, now, edge, agreement, verify_signature):
        return (
            self.valid(cert, obs, now, verify_signature)
            and cert.u >= self.u_min
            and self.refines(cert.kappa, edge)
            and agreement >= self.a_min
        )


class SelfSupervisedMonitor:
    def __init__(self, encoder, teacher=None, alpha=0.05):
        self.encoder = encoder
        self.teacher = teacher
        self.alpha = alpha
        self.q_n = None
        self.a_min = None
        self.q_pred = 1.0
        self.q_proto = 1.0

    def novelty_raw(self, obs):
        z = self.encoder(obs)
        pred_err = self.encoder.prediction_error(obs)
        proto = min(np.linalg.norm(z - mu) for mu in self.encoder.prototypes)
        return pred_err, proto

    def novelty(self, obs):
        pred_err, proto = self.novelty_raw(obs)
        return 0.5 * (pred_err / self.q_pred + proto / self.q_proto)

    def agreement(self, obs):
        if self.teacher is None:
            return 1.0
        ze, zc = self.encoder(obs), self.teacher(obs)
        denom = np.linalg.norm(ze) * np.linalg.norm(zc) + 1e-9
        return float(np.dot(ze, zc) / denom)

    def calibrate(self, nominal_obs):
        preds, protos = zip(*(self.novelty_raw(o) for o in nominal_obs))
        self.q_pred = float(np.median(preds)) or 1.0
        self.q_proto = float(np.median(protos)) or 1.0
        scores = [self.novelty(o) for o in nominal_obs]
        agrees = [self.agreement(o) for o in nominal_obs]
        self.q_n = float(np.quantile(scores, 1.0 - self.alpha))
        self.a_min = float(np.quantile(agrees, self.alpha))

    def governor(self, obs):
        return int(self.novelty(obs) <= self.q_n
                   and self.agreement(obs) >= self.a_min)


def cessl_step(M, s, obs, now, cloud_cert, verify_signature,
               guard, monitor, v7_step):
    edge = v7_step.local_advice(M, s)
    a = monitor.agreement(obs)
    accepted = (
        cloud_cert is not None
        and guard.accept(cloud_cert, obs, now, edge, a, verify_signature)
    )
    kappa = cloud_cert.kappa if accepted else edge

    if accepted and kappa["type"] == "grasp":
        if not M.grasp.check(kappa["iota"]):
            kappa, accepted = edge, False

    g = monitor.governor(obs)
    eta_eff = M.otl.eta * g
    beta_eff = M.er.beta * g

    result = v7_step(M, s, obs, kappa=kappa, eta=eta_eff, beta=beta_eff)
    trace = {
        "accepted": accepted,
        "gate": g,
        "agreement": a,
        "novelty": monitor.novelty(obs),
        "kappa": kappa,
    }
    return result, trace
```

## 4. 推导

**引理 77（云端建议保守性）** 若 `Accept(C,o,t)` 成立，则云端建议 κ 不可能是对 M₀/M₁ 的放松。证明：Accept 蕴含 κ ⪯_safe κ_e；由定义 531，安全层阈值逐分量不减、动作集为子集、指令类型合法。v7 的局部闭环已保证 κ_e 满足 M₀，安全细化只会使可行域更小，故 M₀ 仍满足。∎

**引理 78（陈旧证书安全界）** 设安全裕度 g(s) 为 L_g-Lipschitz，状态相对速度不超过 v_max，且采纳时初始裕度至少 ε_m。若 `Δ(C,t) ≤ ε_m/(L_g·v_max)`，则使用该证书时 M₀ 在有效期内保持。证明：在 Δ 时间内状态变化不超过 v_max·Δ，故裕度下降不超过 L_g·v_max·Δ ≤ ε_m；由引理 77，云端不会降低 M₀ 阈值，因此剩余裕度非负。∎

**引理 79（冲突取保守者的安全性）** 若两个云端证书 κ₁、κ₂ 都满足 κ_j ⪯_safe κ_e，则其逐分量取大阈值、动作集取交的 meet `κ₁ ⊓ κ₂` 仍满足 `κ₁⊓κ₂ ⪯_safe κ_e`。证明：逐分量取大保持 τ_i(κ)≥τ_i(κ_e)（i=0,1）；交集是各自动作集的子集，故也是 κ_e 动作集的子集；类型合法性由构造保持。∎

**引理 80（错误冻结率上界）** 在可交换性假设下，用共形分位数 q_{1−α} 校准新颖度，则对同分布的新样本有 `P(g(o)=0) ≤ α + 1/(m+1)`，其中 m 为校准样本数。证明：标准 split-conformal 覆盖界给出 `P(n(o) ≤ q_{1−α}) ≥ 1−α−1/(m+1)`；g=0 还需 a<a_min，故其概率不超过新颖度越界概率。∎

**引理 81（信任门的退化正确性）** 当 `g(o)=0` 时，η_eff=0、β_eff=0，OTL 停止更新、ER 退回风险权重；该控制步的指标层级、抓取几何检查与局部闭环仍由 v7 执行。因此该步行为等价于 v7 在固定阈值下的保守配置。∎

**引理 82（组合退化等价性）** ① 云端失效 ⇒ 无证书被接受，κ=κ_e，其余模块不变，行为等价 v7；② SSL 失效 ⇒ 由定义 542 同时禁用云证书，行为等价 v7；③ v7 的 OTL/GCT/ER 失效 ⇒ 由 v7 已证明的退化链等价 v6。三步互不触发级联，因为每步只依赖上一层的本地接口。∎

**推论 83（云端不能单独造成硬约束违背）** 由引理 77 与 78，任何被接受的云端建议在有效期内都保持 M₀；云端若试图放松安全层或绕过 γ_grasp，Accept 直接为假。故云端只可能提高性能或保持现状，不能成为新的硬安全风险源。

## 8. 本轮最大风险

**一句话**：自监督门控若把“分布内但任务关键”的罕见状态误判为 OOD，会过度冻结适应，使系统在真正需要云/在线适应的长尾场景中反而退化；而云端证书的时钟同步与签名链一旦被破坏，安全细化假设会在陈旧证书上失效。
