# 第 44 轮（新循环第 4 轮） · MuJoCo-Grounded × Deployment-Auditable：把「可复现证书」与「落地验收」接进可信闭环（四层架构 v9）

> 承接第 43 轮 v20（Persona-Cert × Concurrent-Cert）。v20 自陈的最大风险是「共形只保边际覆盖 + 多用户契约空集」，但那只在统计与协商层；它底下还压着两个更致命的假设：**(H1) 证书的 soundness 只在一个仿真源（Isaac Sim）里自证，且没有第三方可复现的物理基准**——是「我信」而非「你验」；**(H2) 仿真到真机的差距被默认为 0**——margin、θ、租约全都建立在「仿真即现实」上，而体系里没有「现实差距」这一项。本轮灵感词「MuJoCo」「应用落地」精确命中这两点：**MuJoCo** 作为社区共识、接触丰富、确定性可复现、GPU 大规模并行的物理引擎，可被提升为**第三方复现预言机**；**应用落地** 迫使证书从仿真里的数学对象，变成能绑定硬件、能通过验收、能在现场被撤销的**部署证书**。二者耦合出新的核心度量 **现实差距预算 ĝ**：证书只有满足 m − ĝ ≥ θ 才允许转移——扩张不再靠信念，而靠可测差距。

## 0. 直觉与动机

**灵感 1（MuJoCo → 可复现性就是证据）**：直觉上，一个只在作者自己仿真里成立的证书，和没有证书差不多；反过来，任何人拿到 MJCF 模型 + 动作轨迹 + 种子 + 引擎版本，就能逐帧重放并独立给出通过/失败——这把「相信我」变成「你自己跑」。所以把 MuJoCo 提升为 **Replay Oracle（MRO）**：证书必须携带**证据包**（模型哈希、控制器/依赖哈希、轨迹、种子、版本、容差），任何审查者都能复现。**严谨点**：MuJoCo 的确定性只是「同版本/同平台/同编译标志」的确定性，跨平台是**浮点等价类**问题；接触事件（非光滑）对 ε 级扰动可能翻转顺序。因此必须区分「状态 ε-重现」与「接触事件序列稳定」，重放不稳定就拒绝证书，而不是假装可复现。

**灵感 2（应用落地 → 证书要能上产线，不只是论文里 sound）**：落地失败往往不在算法，而在**证据链断裂**：模型换了、硬件批次变了、实时内核升了、标定漂了，证书却还是那张。于是引入 **Deployment Certificate（DAC）**：证书绑定硬件序列号、SBOM、RT 内核补丁级别、标定版本与 MuJoCo 模型哈希；上电做度量启动（measured boot），运行中做现场漂移监测，任一处不匹配即证书作废并退到安全模式。这把 v20 的「租约新鲜度」从**时间维**扩展到**来源/身份维**。

**灵感 3（耦合 → 差距预算 ĝ 是可转移的货币）**：MuJoCo 给的是可复现的仿真分布，落地要的是对真机的信任；桥不是「相信仿真」，而是**可测的现实差距预算 ĝ**。用可微 MuJoCo（MJX）做系统辨识，用共形/区间方法给出差距上界，再把 ĝ 作为证书边际的**通胀项**：m̃ = m − ĝ。规则很硬：**m − ĝ ≥ θ + δ_est 才允许转移**；ĝ 太大则证书不许落地（而非偷偷放宽）。这把 v20 的「收缩免费、扩张持证」升级为「转移持证、落地验价」。

**耦合升级**：MRO（复现预言机）产出可独立复核的证据包；RGB（现实差距预算）产出分 ODD 区域的 ĝ 表并把边际通胀编译进 IP-51/IP-53；DAC（部署证书）把证书绑定到设备、验收与撤销。四层架构由 v8（仿真-检索-边缘 + 人格 + 并发）升级为 v9（+ 复现证据层 + 现实差距层 + 部署验收层）。

## 1. 形式化定义（增量：定义 44–49）

**定义 44（可复现证书与证据包）**：证据包 E=(h_MJCF, h_ctrl, h_deps, τ, seeds, v_engine, ε, h_platform)，其中 τ={(x_t,u_t)}_{t=0..T} 为状态-动作轨迹，h_* 为规范序列化后的哈希。重放算子 R(E) 产出轨迹 z'_{0..T}。证书 C 称为 **ε-可复现**，当且仅当：(i) 逐步状态偏差 sup_t‖z'_t−z_t‖ ≤ ε；(ii) 接触事件多重集一致（接触对与法向冲量符号），或事件序列被分类为 *稳定*。**平台等价类** [E]_ε={E' : R(E') 与 R(E) 在 ε 内等价}。**命题（证据充分性）**：若 C 由守卫谓词定义且 R(E) 满足全部守卫、事件稳定，则复核方无需信任签发方即可判定 C 成立。

**定义 45（现实差距预算与转移判据）**：令差距随机变量 G=d(z_real,z_sim)（d 取轨迹上确界或分布 Wasserstein）。用配对真机/仿真 rollout 的非一致性分数构造分 ODD 单元的 Mondrian 共形上界 ĝ_{1−β}，使可交换性下 P(G ≤ ĝ) ≥ 1−β。**转移判据**：Transfer(C) ⇔ m(C) − ĝ ≥ θ + δ_est，δ_est 为估计器余量。**边际通胀**：m̃=m−ĝ（只减不增，sound-by-construction）。**警告**：分布漂移破坏可交换性，故 ĝ 必须按 ODD 单元分段维护并加权校准，单一全局 ĝ 会系统性低估。

**定义 46（差距感知转移定理）**：设仿真在时域 H 上证书 margin 为 m，真实与仿真轨迹差 ≤ ĝ，且守卫余量关于状态是 L_g-Lipschitz。则真实 margin ≥ m − L_g·ĝ。**推论**：若 m ≥ θ + L_g·ĝ，则真实系统在 H 上保持不变式 I。转移不是「相信仿真」，而是把 ĝ 显式买进安全预算。

**定义 47（部署证书与度量启动）**：D=(h_C, h_E, hw_id, h_SBOM, k_rt, calib_id, [t0,t1], σ_sig, std_map)。**启动判定** Att(device,D) ⇔ 证据哈希、硬件序列号、RT 内核版本、标定哈希与签名全部匹配。**状态机** Issued→Active→Suspended(drift)→Revoked；任一不匹配即 Void 并进入安全模式。**绑定格** D1≼D2 表示 D1 的适用范围蕴含 D2（硬件更窄、窗口更短）；多机/多人格证书按格求交，交集为空则不得部署。

**定义 48（现场漂移监测与撤销）**：以 e-process/检验鞅 M_t 检验「遥测残差与 MuJoCo 参考分布一致」的 H0；Ville 不等式给出误报 ≤ α_f。**撤销判据**：M_t>1/α_f 即 Suspended，重新辨识后重签或 Revoke。**诚实的边界**：这是统计保证，不 sound 对抗任意对抗性漂移；因此对抗性场景必须由定义 49 的验收套件与人工复核兜底，不能把「没报警」当成「无漂移」。

**定义 49（落地验收、ODD 覆盖与标准映射）**：ODD O 为带测度 μ 的条件集合；验收套件 A；覆盖率 cov(A,O)=μ(∪_{a∈A}cell(a))/μ(O)。**部署许可** ⇔ 全部 a∈A 通过 ∧ cov≥γ ∧ Transfer(C) ∧ Att(D)。**运营证书** O-cert=(D,A,cov)。标准映射：ISO 10218-1/-2 与 ISO/TS 15066（协作机器人）、ISO 3691-4（AGV）、ISO 13849-1（PL）、IEC 61508（SIL）、ISO 21448 SOTIF（未知不安全场景）、EU AI Act 第 9/15 条（风险管理与准确性/鲁棒性/网络安全）。**关键洞察**：ĝ 与 ODD 覆盖率正是 SOTIF 意义上的「已知不安全场景」量化，使证书语言与合规语言可对齐。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-60 MUJOCO-REPLAY-ORACLE（MRO）
1. **证据包规范**：CBOR/JSON 规范序列化 + Merkle 哈希，含 MJCF、SBOM、控制器二进制哈希、轨迹、种子、MuJoCo 版本、编译标志、积分器/求解器参数。
2. **确定性重放器**：固定工具链；接触事件差分器把重放分为 stable / marginal / unstable，unstable 直接拒绝证书（安全优先）。
3. **跨引擎/跨平台差分**：MuJoCo vs Isaac vs 真机日志三方差分，超 ε 即标记 diverge 并回灌。
4. **公开复核器 + CI 闸门**：每个新证书必须附带重放证据包，否则 CI 不通过。

### 2.2 IP-61 REALITY-GAP-BUDGET（RGB）
1. **可微系统辨识**：MJX 并行 rollout，拟合质量/惯量/摩擦/执行器增益/延迟等参数，反向传播最小化轨迹损失。
2. **差距上界估计**：配对 rollout + 分 ODD 单元 Mondrian 共形，输出 (1−β) 上界 ĝ 表；漂移时按重要性加权重校准。
3. **边际通胀与转移闸门**：m̃=m−ĝ 编译进 IP-51 守卫与 IP-53 阈值；不满足转移判据则拒绝签发部署证书。
4. **主动缩差**：按 Fisher 信息/D-最优选择最有信息量的辨识实验，把高 ĝ 区域主动降下来；规划器同时规避高 ĝ 风险区。

### 2.3 IP-62 DEPLOYMENT-ACCEPTANCE-CERT（DAC）
1. **证书格式与签发**：Ed25519 签名 + 硬件根信任（TPM/安全区）+ SBOM（SPDX/CycloneDX）+ 标定 blob 哈希。
2. **度量启动与周期证明**：上电与运行期采样哈希校验；不匹配即 Void→安全模式；支持远程证明。
3. **现场漂移与撤销**：e-process 监测遥测-参考残差；自动 Suspended；操作员复核后重签；车队按谱系召回共享缺陷。
4. **验收 harness 与合规包**：ODD 网格 + 脚本/模糊测试；自动生成标准映射文档。

## 5. 本轮最大风险

**一句话**：现实差距预算 ĝ 若只在平滑可观测参数上做区间化，就会在**接触事件**（非光滑、非可微、对参数极敏感）处系统性低估——于是「已在 MuJoCo 复现」会被误当成「能在真机落地」，这正是把 soundness 从证明层偷渡到部署层的最大漏洞。

```
def canonical_bundle(model_path, ctrl_bin, trace, seeds):
    return Bundle(
        h_mjcf   = sha256(canonicalize_mjcf(model_path)),
        h_ctrl   = sha256(ctrl_bin),
        h_deps   = merkle_hash(sbom()),

def replay_verify(bundle, guards):
    z = mujoco_rollout(bundle, bundle.trace.actions)          # 固定工具链
    cls = contact_event_stability(z, bundle.trace.events, bundle.eps)
    if cls == "unstable":
        return Verdict(False, "contact-unstable")              # 安全优先：拒绝
    for t, g in guards:
        if min_guard_margin(g, z[t]) < g.theta - bundle.eps:
            return Verdict(False, f"guard@{t}")
    return Verdict(True, cls)

def cross_engine_diff(bundle, engines=("mujoco", "isaac")):
    traces = {e: rollout(e, bundle) for e in engines}
    return {pair: sup_dist(traces[a], traces[b]) for a, b in pairs(engines)}
```

### IP-61 RGB：MJX 辨识、差距上界与转移闸门
```
def fit_dynamics_mjx(real_logs, init_params, iters, lr, envs=4096):
    p = init_params
    for _ in range(iters):
        sim  = mjx_parallel_rollout(p, real_logs.actions, envs=envs)  # GPU 并行
        loss = trajectory_loss(sim, real_logs)
        p    = p - lr * grad(loss, p)                                  # 可微物理
    return p

def estimate_gap_table(pairs, beta):
    table = {}
    for cell in odd_cells(pairs):                  # 按 ODD 单元分层（Mondrian）
        d = [dist(r.real, r.sim) for r in pairs if r.cell == cell]
        table[cell] = conformal_upper(d, 1 - beta) # 共形上界，非正态假设
    return table

def transfer_gate(cert, gap_table, delta_est):
    return (cert.margin - gap_table[cert.odd_cell]) >= cert.theta + delta_est

def inflate(cert, gap_table):
    return cert.margin - gap_table[cert.odd_cell]  # 只减不增 => sound by construction

def active_gap_reduction(candidate_experiments, gap_table):
    # 选 Fisher 信息 / D-最优实验，优先压高 ĝ 单元
    return argmax(candidate_experiments,
                  key=lambda e: fisher_info(e, gap_table) / cost(e))
```

### IP-62 DAC：签发、证明、漂移与验收
```
def issue_deployment_cert(cert, evidence, device, calib, window, std_map):
    D = DeploymentCert(h_C=hash(cert), h_E=hash(evidence),
                       hw_id=device.serial, h_sbom=hash(sbom()),
                       k_rt=device.kernel, calib_id=hash(calib),
                       window=window, std_map=std_map)
    return D.sign(issuer_key)                    # Ed25519

def attest(device, D):
    return (device.loaded_evidence_hash == D.h_E and
            device.serial == D.hw_id and
            device.kernel == D.k_rt and
            device.calib_hash == D.calib_id and
            verify_sig(D, issuer_pubkey) and
            D.window.contains(monotonic_now()))

def field_drift_monitor(telemetry, reference, alpha_f):
    M = 1.0
    for x_t in telemetry:
        M *= likelihood_ratio(x_t, reference)    # e-process / 检验鞅
        if M > 1 / alpha_f:                      # Ville: H0 下误报 ≤ α_f
            return SUSPENDED
    return ACTIVE

def deployment_admissible(D, C, A, O, gap_table):
    return (attest(D.device, D) and
            all(a.pass_ for a in A) and
            coverage(A, O) >= GAMMA and
            transfer_gate(C, gap_table, DELTA_EST))

def acceptance_harness(ODD_grid, fuzz_budget):
    results = [run_case(c) for c in ODD_grid] + fuzz(ODD_grid, fuzz_budget)
    return Suite(results, coverage=covered_measure(results, ODD_grid))
```

```
def car_transition_guard(e, x, cert_obj, persona, lease, gap_table, t):
    theta   = cert_obj.alpha_e[e] * cert_obj.theta_sim[e]
    m_lookup = cert_lookup_L0(x).m_lo[e]
    m_lease  = lease.m - lease.lam * (t - lease.tau)
    m_cap    = persona_cap[e](persona)
    g        = gap_table[cert_obj.odd_cell]
    return min(m_lookup, m_lease, m_cap) - g >= theta and lease_valid(lease, theta, t)

def monitor_step_odd(x, cell_id, gap_table):
```

## 5. 风险与缓解（增量）

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 接触事件非光滑，ĝ 在接触处系统性低估，「仿真可复现」被误当「真机可落地」 | 高 | E96/E97 红线；接触事件单独分层校准；高接触区提高 ĝ 保守因子；不达标禁止转移 |
| MuJoCo 跨平台/跨版本浮点非确定性，证据包无法复现 | 高 | 锁工具链 + 记录编译标志/求解器参数；事件稳定性分类；不稳定即拒证；容器化复核环境 |
| 差距上界 ĝ 过松，导致几乎所有证书都不能转移（可用性崩塌） | 高 | 分 ODD 单元 ĝ；主动缩差（Fisher/D-最优）；允许声明更小 ODD 换取可转移 |
| 部署证书绑定开销大、误作废，影响正常运行 | 中-高 | 证明卸载硬件根信任；启动只校验关键哈希；周期证明可配置；误作废需人工复核 |
| 现场漂移是统计检测，不 sound 对抗对抗性漂移 | 中-高 | e-process + 人工复核兜底；对抗场景纳入 IP-59；不得把「未报警」当「无漂移」 |
| 标准映射流于形式，无法真正支撑认证 | 中 | 映射表由合规专家审阅；每个标准条款绑定可执行证据项；审计留痕 |
| MJX 可微辨识在真实接触下梯度失真，参数辨识偏 | 中 | 用真实接触事件做分段校验；参数不确定性用区间而非点估计；辨识实验主动设计 |

## 6. 本轮最大风险

**一句话**：现实差距预算 ĝ 若只在平滑可观测参数上做区间化，就会在**接触事件**（非光滑、非可微、对参数极敏感）处系统性低估——于是「已在 MuJoCo 复现」会被误当成「能在真机落地」，这正是把 soundness 从证明层偷渡到部署层的最大漏洞。
