# 第 44 轮（新循环第 4 轮） · Scenario-Flow-Cert：把「场景分布」与「流匹配策略」纳入可验证证书闭环（四层架构 v9）

> 承接第 43 轮 v20（Persona-Cert × Concurrent-Cert）。v20 自陈最大风险是「共形边际覆盖 + 多用户契约空集」，但它在安全证明的最底层还压着两个更隐蔽的假设：**(H3) 场景被视为独立同分布的固定基准集**——证书只在「验证场景」上 sound，从未声明对**部署场景分布漂移**是否 sound，于是「场景欺骗」（benchmark overfit / scenario-fooling）可以静默地让证书失效；**(H4) 策略被视为可任意认证的确定性 oracle**——但真实策略正走向**生成式**（流匹配/扩散），其 ODE 采样对状态扰动的放大因子 e^{L_v T} 会直接击穿几何证书的 margin 假设，而现有 IP-48「认证流匹配」只认证单条固定轨迹，没有分布级、场景条件化、可对抗的保证。本轮灵感词「场景驱动创新」「流匹配策略」正好命中这两个假设：**场景驱动创新**要求把「场景」从测试数据升格为**可传输的概率测度**，用最优传输（OT）定义 ODD 鲁棒球；**流匹配策略**要求把生成式策略的**速度场 Lipschitz 常数**变成证书的一部分。二者耦合处出现本轮真正的新对象：**同一个 OT 流既定义了证书要覆盖的场景球，又给出了找到反例的攻击方向**——流既是保守性的来源，也是测试的武器。

## 0. 直觉与动机

**灵感 1（场景驱动创新 → 场景不是测试集，而是可传输的测度）**：传统做法是「多测几个场景」。但「多」没有方向，也没有边界：测了 10 万个晴天场景，也证明不了雨天分布偏移下安全。场景驱动创新应当问：**部署场景分布 μ_deploy 距离我验证过的 μ̂_n 有多远？在这个距离内证书还成立吗？** 于是把场景写成场景空间 S 上的概率测度，用 2-Wasserstein 距离定义 ODD 鲁棒球 ODD_ρ={μ: W₂(μ,μ̂_n)≤ρ}，并要求证书对整个球一致 sound。这样「创新」由场景空间的**几何**驱动，而非由灵感随机性驱动：ρ 就是「我愿意为鲁棒性付多少保守性」的旋钮，而它必须有可识别的统计含义（见定义 47 的可识别性注记）。

**灵感 2（流匹配策略 → 确定性 ODE 是认证的礼物，也是放大器的诅咒）**：流匹配学习一个速度场 v_θ(z,t,s)，从噪声 z₀ 积分到动作 z₁，p₁=(Φ_θ)_#p₀。相比扩散的随机 SDE，它是**确定性 ODE**：同一初值必得同一动作，可复现、可区间验证，这是认证的礼物。但它也是放大器：若 v_θ 关于状态是 L_v-Lipschitz、关于场景条件是 L_s-Lipschitz，则流映射的扰动放大至多 e^{L_v T}（Gronwall）。深度网络的经验 Lipschitz 常数往往很大，于是「名义场景很安全」的证书会在相邻场景瞬间失效。解法不是放弃生成式策略，而是**把 L_v、L_s 变成必须认证、必须报告的量**：用谱归一化/区间界传播（CROWN）给出可证上界，并让 margin 预算显式扣除 L_Φ·ρ。

**灵感 3（耦合 → 同一个流，既是保守来源，也是攻击方向）**：这是本轮最关键的一步。OT 球给了「证书必须覆盖的最坏邻居」，而**沿 OT 流把场景分布朝低 margin 区域推**，恰是一个有方向的对抗场景生成器（Wasserstein 梯度流）。于是场景流与策略流构成**双向流匹配**：前向用策略流把场景扰动映射为动作扰动（求上界），反向用场景流把动作失败回溯为场景方向（找反例）。证书的**紧性**因此可度量：双向流的 OT 对偶间隙越小，证书越不保守。这把 v20 的「共形覆盖」从「按人格的条件覆盖」进一步推进到「按场景邻域的分布级覆盖」。

**耦合升级**：SME（场景流形引擎）维护场景测度、场景契约与 ODD 球；FMCE（流匹配证书引擎）认证速度场 Lipschitz 并签发流证书；SFV（场景流验证器）用 OT 梯度流生成对抗场景并把「失败邻域」回灌 CKB/SCV。四层架构由 v8「人格契约 + 并发证书」升级为 v9「场景流形 + 流策略证书」。场景漂移同时成为定义 41 证书租约的**失效源**：一旦 W₂ 漂移超阈，租约立即作废重颁，把「场景」接进已有的并发-新鲜度闭环。

## 1. 形式化定义（增量：定义 44–49）

**定义 44（场景测度、场景契约与 ODD 鲁棒球）**：场景空间 S⊆R^m 由场景文法 g 生成（天气 w、人群密度 d、人格 u、任务 τ、几何 γ 的笛卡尔积经可行性约束裁剪）。部署场景分布 μ_deploy 为 S 上概率测度，现场日志给出经验测度 μ̂_n。**ODD 鲁棒球** ODD_ρ = {μ : W₂(μ, μ̂_n) ≤ ρ}，ρ≥0。**场景契约** Σ(σ) ⊆ C_global 由场景特征 σ(s) 参数化（能见度→速度上限、人群密度→接触力上限、地面摩擦→刹车距离下限）。**场景条件证书** C(s,u) = C_global ∩ Π_u ∩ Σ(σ(s))。**命题**：Σ 单调收缩 ⟹ C(s,u) ⊆ C_global，场景建模不引入新的 soundness 债务（与定义 38 同构）。

**定义 45（场景覆盖与 OT-鲁棒 soundness）**：设 Safe(s)⊆A 为场景 s 下满足 margin(s,a)≥θ 的动作集。**场景覆盖**：证书在场景集 S_c 上成立，若 μ̂_n(S_c) ≥ 1−β。**OT-鲁棒 soundness**：∀μ∈ODD_ρ，μ({s: 策略在 s 下违例}) ≤ β。**注**：这严格强于逐点 soundness——逐点只保证 μ̂_n 上，OT 球才约束部署。**命题（保守性代价）**：ρ↑ ⟹ ODD_ρ↑ ⟹ 需覆盖场景↑ ⟹ 可行证书集↓；ρ=0 退化为逐点 sound。**推论**：ρ 不能任意取大，也不该拍脑袋取小，必须由有限样本的 W₂ 收敛/自助界给出，否则鲁棒性既未证明也未证伪。

**定义 46（认证流匹配策略与速度场 Lipschitz）**：流匹配策略 p₁=(Φ_θ)_#p₀，Φ_θ 由 ODE dz/dt = v_θ(z,t,s)，t∈[0,1] 定义，条件场景 s。训练用条件流匹配损失 E_{t,z₀,z₁,s}‖v_θ((1−t)z₀+t z₁, t, s) − (z₁−z₀)‖²。**认证 Lipschitz**：若对任意 (z,z',s,s',t) 有
‖v_θ(z,t,s) − v_θ(z',t,s')‖ ≤ L_v‖z−z'‖ + L_s‖s−s'‖，
则由 Gronwall，流映射满足
‖Φ_θ(z₀,s) − Φ_θ(z₀',s')‖ ≤ e^{L_v}‖z₀−z₀'‖ + ((e^{L_v}−1)/L_v)·L_s‖s−s'‖。
记联合放大 L_Φ = max{e^{L_v}, (e^{L_v}−1)L_s/L_v}。L_v、L_s 必须由区间界传播/谱范数给出**可证上界**，而非经验估计；这一点是定义 47 能成为定理而非启发式的前提。

**定义 47（流证书与分布级 soundness）**：给定名义场景 s、流映射 Φ_θ、ODD 半径 ρ 与积分误差界 ε_ode。**流证书** FlowCert(θ,s,ρ) 成立，当且仅当
(a) 名义动作 a=Φ_θ(z₀,s) 满足 margin(s,a) ≥ θ + L_Φ·ρ + ε_ode；
(b) L_v,L_s 可证且生成过程无采样随机性（确定性 ODE）。
**定理（流证书 soundness）**：若 FlowCert 成立，则对 ∀s' 满足 ‖σ(s')−σ(s)‖ ≤ ρ，动作 a'=Φ_θ(z₀,s') 仍满足 margin(s',a') ≥ θ。**证明**：由定义 46，‖a−a'‖ ≤ L_Φ‖σ(s)−σ(s')‖ ≤ L_Φρ；由 margin 对动作的 1-Lipschitz 性与三角不等式，margin(s',a') ≥ margin(s,a) − L_Φρ − ε_ode ≥ θ。∎
**推论（分布级）**：对任意 μ∈ODD_ρ，若所有 s 满足流证书，则违约测度 μ(unsafe) ≤ β。
**可识别性注记**：ρ 应由 μ̂_n 的 W₂ 样本复杂度（n^{−1/m}）或自助法置信上界给出；过大的 ρ 会让流证书直接不可行，过小的 ρ 只是自欺的逐点证书。这一点由 E95 实测。

**定义 48（场景流测试生成：Wasserstein 梯度流）**：定义证书缺口泛函 G(s)=θ−margin(s,Φ_θ(z₀,s))（G>0 即危险）。场景流 ν_t 由速度场 u(s,t)=−∇_s G_ε(s)（G_ε 为平滑版）驱动，ν₀=μ̂_n，ν₁ 沿最速下降方向集中到低 margin 区。**定理（攻击有效性）**：若 ν₁({G>0}) ≥ γ，则对任意 μ 满足 W₂(μ,ν₁)≤δ，有 μ({G>0}) ≥ γ − L_G·δ，其中 L_G 为 G 的 Lipschitz 常数。**推论**：场景流找到一个反例 s* 后，其 OT 邻域内都是反例——把「单点失败」升级为「失败邻域」，成为 ODD 收缩或策略重训的可操作输入。**注**：这是攻击器，不承担 soundness，只承担「更快证伪」。

**定义 49（场景-策略双向流匹配与证书紧性）**：策略流 Φ^P_θ（前向）与场景流 Φ^S_φ（反向）构成双向匹配。**min-max 证书问题**：
min_θ max_{μ∈ODD_ρ} E_{s~μ}[risk(Φ^P_θ(·,s))]  s.t. FlowCert(θ,s,ρ) ∀s。
**紧性度量**：κ = (证书违约上界 − 场景流实测违约) / 证书违约上界 ∈ [0,1]；κ→1 表示证书不保守。**命题（对偶紧性，启发式）**：若 risk 关于 s 凸且 ODD_ρ 为 OT 球，则内层 max 可由场景流的一阶最优传输计划逼近，双向流不动点处 κ 单调不减。**注**：该命题**不作为 soundness 前提**；soundness 永远只依赖定义 47，κ 仅是可用性/效率指标，并由 E100 实测。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-60 SCENARIO-MANIFOLD-ENGINE（场景流形引擎 SME）
1. **场景文法与测度估计**：场景文法 g 生成 S；μ̂_n 由现场日志经经验测度/核密度估计；自助法给出 W₂ 置信上界 → 可识别 ρ。
2. **场景契约编译**：σ(s)→速度/接触力/刹车/区域上限 → Σ(σ(s))，与 Π_u 求交得 C(s,u)。
3. **ODD 漂移检测**：在线估计 μ_deploy 与 μ̂_n 的 W₂；超阈值即触发证书租约失效（接入定义 41）与证书重颁。
4. **失败邻域回灌**：场景流反例 s* 的 OT 邻域打包为「失败场景族」写入 CKB。

### 2.2 IP-61 FLOW-MATCH-CERT-ENGINE（流匹配证书引擎 FMCE）
1. **可证 Lipschitz 速度场**：谱归一化 + CROWN/区间界传播给出 L_v、L_s 上界；报告而非隐藏。
2. **流证书签发**：按定义 47 签发 FlowCert，margin 预算显式扣除 L_Φρ+ε_ode。
3. **积分误差界**：固定步长 RK 的局部截断误差累计界 ε_ode，纳入证书。
4. **回退控制器**：FlowCert 不成立时切换到已验证的解析安全策略（CBF/查表），绝不裸用未认证生成动作。

### 2.3 IP-62 SCENARIO-FLOW-VALIDATOR（场景流验证器 SFV）
1. **OT 梯度流对抗生成**：按定义 48 生成最坏场景，输出失败邻域而非单点。
2. **双向流紧性评估**：估计 κ，指导 ρ 与网络 Lipschitz 正则强度。
3. **场景覆盖审计**：按场景文法分层报告覆盖与未覆盖角（对抗「场景欺骗」）。
4. **漂移长时程回放**：在 Isaac Sim 注入分布漂移，检验 E98/E102。

## 5. 本轮最大风险

**一句话**：流匹配速度场的**可证 Lipschitz 上界会随网络深度/时间积分指数级变松**（e^{L_v}），使流证书要么把安全集压成空集而「真空 sound」，要么被迫用经验 Lipschitz 回填、从而把「场景欺骗」原样请回来；叠加 ODD 半径 ρ 在有限现场日志下不可识别，本轮真正的单点失败是「**证书要么不可用、要么不可信**」，因此 E95（ρ 可识别性）与 E96（可证 L_v 紧性）必须设为红线，并保留「退回解析 CBF 策略」这条永不失 sound 的底线。

## 2. 关键算法（伪代码）

### IP-60 SME：场景测度、可识别 ODD 与漂移检测
```
def estimate_odd_radius(logs, alpha, B=200):
    mu_hat = empirical_measure(logs)
    rhos = []
    for _ in range(B):
        resample = bootstrap(logs)
        rhos.append(wasserstein2(empirical_measure(resample), mu_hat))
    return quantile(rhos, 1 - alpha)        # 可识别的 rho 上界

def compile_scenario_contract(s):
    return ScenarioContract(
        speed_max = f_visibility(s.visibility),
        force_max = f_crowd(s.crowd_density),
        brake_min = f_friction(s.friction),   # 摩擦低 => 刹车距离下限大
        region    = g.region(s))

def detect_drift(deploy_samples, mu_hat, rho, eps_w):
    d = wasserstein2(empirical_measure(deploy_samples), mu_hat)
    if d > rho + eps_w:
        return DriftEvent(d, action='invalidate_lease_and_recertify')
    return None
```

### IP-61 FMCE：可证 Lipschitz、流证书与回退
```
def certify_velocity_field(v_theta, z_domain, s_domain, eps):
    L_v = crown_lipschitz(v_theta, wrt='z', domain=z_domain) + eps
    L_s = crown_lipschitz(v_theta, wrt='s', domain=s_domain) + eps
    return L_v, L_s                        # 必须上报，禁止用经验值顶替

def flow_certificate(v_theta, z0, s, rho, theta, eps_ode):
    L_v, L_s = certify_velocity_field(v_theta)
    L_phi = max(exp(L_v), (exp(L_v) - 1) * L_s / max(L_v, eps_ode))
    a = integrate_rk(v_theta, z0, s, eps=eps_ode)   # 确定性 ODE，无采样噪声
    m = margin(s, a)
    ok = (m >= theta + L_phi * rho + eps_ode)        # 定义 47 (a)
    return FlowCert(ok=ok, m=m, L_phi=L_phi, rho=rho, eps_ode=eps_ode)

def act_or_fallback(obs, s, z0, theta, rho):
    fc = flow_certificate(policy.v_theta, z0, s, rho, theta, EPS_ODE)
    if fc.ok and lease_valid(scenario_lease, theta, monotonic_now()):
        return integrate_rk(policy.v_theta, z0, s, EPS_ODE)
    return analytical_cbf_controller(obs)    # 永不失 sound 的底线
```

### IP-62 SFV：Wasserstein 梯度流攻击与双向流紧性
```
def scenario_flow_attack(v_theta, mu_hat, steps=50, eta=0.05):
    nu = sample(mu_hat, n=4096)
    for _ in range(steps):
        g = grad_cert_gap(nu, v_theta)       # dG/ds，经策略流反传
        nu = project_to_odd(nu - eta * g)    # OT 梯度流一步（投影回 ODD）
    failing = [s for s in nu if cert_gap(s, v_theta) > 0]
    return failing, ot_neighborhood(failing, delta=ETA_NEIGH)

def tightness_kappa(upper_violation, measured_violation):
    if upper_violation <= 0:
        return 1.0
    return (upper_violation - measured_violation) / upper_violation
```

### IP-51/52/56 升级：流-场景感知的守卫与租约
```
def car_transition_guard(e, x, cert_obj, persona, scen_contract, flow_cert, lease, t):
    theta = cert_obj.alpha_e[e] * cert_obj.theta_sim[e]
    m_lookup = cert_lookup_L0(x).m_lo[e]
    m_lease  = lease.m - lease.lam * (t - lease.tau)
    m_cap    = persona_cap[e](persona)
    m_scen   = scen_contract.cap(e)           # 场景契约只做上限收缩
    m_flow   = flow_cert.m - flow_cert.L_phi * flow_cert.rho - flow_cert.eps_ode
    return min(m_lookup, m_lease, m_cap, m_scen, m_flow) >= theta \
           and lease_valid(lease, theta, t)

def scenario_lease(drift, rho, t):
    if drift is not None and drift.d > rho:
        return Lease(m=0.0, tau=t, lam=0.0, kappa=K_SAFETY)  # 立即作废
    return acquire_lease('flow', x, theta, K_GEOMETRY)
```

## 6. 本轮最大风险

**一句话**：流匹配速度场的**可证 Lipschitz 上界会随网络深度/时间积分指数级变松**（e^{L_v}），使流证书要么把安全集压成空集而「真空 sound」，要么被迫用经验 Lipschitz 回填、从而把「场景欺骗」原样请回来；叠加 ODD 半径 ρ 在有限现场日志下不可识别，本轮真正的单点失败是「**证书要么不可用、要么不可信**」，因此 E95（ρ 可识别性）与 E96（可证 L_v 紧性）必须设为红线，并保留「退回解析 CBF 策略」这条永不失 sound 的底线。
