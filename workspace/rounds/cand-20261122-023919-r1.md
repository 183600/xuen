# 第 1 轮（新灵感循环第 1 轮；本轮灵感：「UniBot-V1」×「数据采集」）

> **基线**：上一循环产出 MetricVoiceGauge-NCD-HUTDH-v20 + IP-420–424（感知层：PCA/CTS/CFC/HPC/CFCtrl）。v20 及更早的 v19（DCM/OGCC/CCV/DRS/OGC）、v17（CLP/S2C/HCG/PSV/APS/AMC）全部保留。
> 本轮纪律：**数据采集是证书构造，不是训练前的杂务；统一机器人模型是动作接口，不是安全保证**。本轮只做一件事：把 UniBot-V1 的统一动作令牌与数据采集的覆盖结构，安全地接到证书的**支撑域**与**采集策略**上，使“采集—证书—执行”闭环可审计。

## 0. 直觉与动机

**灵感 1（UniBot-V1 → 统一动作令牌，安全必须外挂而非内生）**
直觉：UniBot-V1 是一个跨本体、跨任务的统一机器人基础模型，输出归一化的动作令牌（action token），而不是某个具体机器人的关节/末端位姿。v20 的证书体系默认 θ 已是具体本体参数；一旦策略统一、本体异构，证书就必须插在“令牌 → 本体参数”的解码处。核心创新：**令牌级证书封装 (UniBot Certificate Wrapper, UCW)**。它把 UniBot-V1 的令牌解码为各本体 θ，并对**令牌量化桶取最坏 θ** 过证书门。关键反直觉点：**统一模型越强，越不能把安全内化进模型**——黑箱泛化不可审计；正确做法是把安全外化成令牌级门（模型只“提出”，证书只“否决”）。

**灵感 2（数据采集 → 采集策略决定证书的支撑域，而非样本数量）**
直觉：传统把数据采集当作训练前的离线准备，越多越好。但证书的“可执行域”实际等于数据覆盖的**支撑域 (support)**：未采到的 (状态, 动作) 单元只能保守判为 UNKNOWN≈不安全。核心创新：**数据即见证 (Data-as-Witness)**——每条采集轨迹是一个证书见证，证书支撑 = 被见证单元的并集；数据量 ≠ 覆盖，必须按**采集溯源 (provenance)** 去重，相关条件下的重复采样对支撑的边际贡献趋近于零。关键反直觉点：**采集越多不等于证书越大**，只有落在“证书边界”上的样本才可能让证书收缩（或经再认证后受控扩张）。

**灵感 3（二者统一 → 证书驱动的主动采集闭环）**
直觉：UniBot-V1 的统一令牌让不同本体共享动作语义，于是证书的“未知边界”可以在令牌空间对齐；主动采集则专采“证书最不确定、而执行最可能到达”的单元。核心创新：**主动证书数据采集 (Active Certificate Data Collection, ACDC)**——把主动学习的目标从“提升模型精度”换成“最小化证书保守性（最大化可执行体积）且保持零碰撞”。关键约束：采集本身不能制造风险，只能在有安全退路的**影子区 (shadow region)** 采集；采集带来的域扩张必须过**再认证屏障 (Re-certification Barrier, RB)**，而不是自动继承。

**三者如何统一**
统一为 v20 之上的**数据-证书层**：UCW 是运行时门（令牌→θ→证书），DPL 是证据账本（谁、在哪、何种条件下采到），ACDC 是采集规划器（离线/影子区），CEST 是跨本体支撑迁移，CCGC 是治理控制器（防采集自证循环）。共享状态 `ζ_data = (provenance_ledger, support_cells, token_gate, acquisition_policy, recert_barrier, mode_data)`。统一接口：**运行时永远先过 UCW 令牌门；ACDC 只能改支撑、不能直接改执行域；任何域扩张必须过 RB；RB 未通过或分布偏移超阈值，则冻结为 v20 固定证书**。

## 1. 研究问题（轮次升级版）

- **Q1（令牌级证书封装）**：如何把 UniBot-V1 的归一化令牌无歧义解码为各本体 θ，并在解码处插入证书门而不破坏 50Hz 实时性？令牌的“语义等价类/量化桶”如何与 v20 的 `Θ_n^col` 对齐，且桶内取最坏 θ 的代价可控？
- **Q2（采集支撑的度量与去重）**：如何定义证书支撑域与有效覆盖，使相关条件下的重复采样不被误计为“覆盖”？provenance 相似度如何复用 v20 的 `G(o)` 谱系签名与环境条件？
- **Q3（主动采集的目标与安全约束）**：如何设计采集函数，使“证书保守性下降/可执行体积上升”最大化，同时保证采集动作本身在影子区内零碰撞？期望收益如何用证书边界单元度量？
- **Q4（再认证与安全继承）**：数据增加后证书可能扩张，如何定义 RB 使 `Exec_v21(D_k) ⊆ Exec_v20(D_k)` 在固定快照下成立，而跨快照只允许“有独立覆盖证明”的受控扩张？如何检测采集分布与部署分布的偏移？

## 2. 设计原则（在 P31–P33 基础上新增 P34–P36）

**P34 数据即见证律（Data-as-Witness）**
定义证书支撑 `Supp(C) = ∪ { cell : W(cell) ≥ τ_s }`，其中 `W(cell) = Σ_i w_i` 为该单元上有效见证权重之和，`w_i = 1/(1+λ·dup(prov_i))` 按 provenance 去重。**未见证单元一律记为 UNKNOWN，并保守映射为不安全**；证书只在 `Supp(C)` 上允许返回 SAFE。**数据量不等于覆盖**：新增样本的边际支撑增益 `ΔSupp/ΔN → 0` 当且仅当其 provenance 与既有样本高度相似。

**P35 主动采集收缩律（Active Collection Contraction）**
采集函数 `a(x) = E[ΔVol_exec(x)] / (cost(x)·(1+risk(x)))`，只在**证书未知边界** `∂UNKNOWN(C) = closure(UNKNOWN) ∩ closure(SAFE)` 上取非零值。**采集动作本身必须通过 v20 CCV，且位于影子区 `S_shadow`（存在无碰撞退出路径）**，否则 `risk(x)=∞`，永不采集。采集带来的域扩张不得自动生效，必须过**再认证屏障 RB**：在新区上做**独立留出碰撞探针**（探针分布必须独立于采集策略）+ 保守 margin；未通过则新区保持 UNKNOWN。**主动采集只能降低保守性，不能绕过证书门**。

**P36 跨体支撑迁移律（Cross-Embodiment Support Transfer）**
UniBot-V1 提供本体不变令牌嵌入 `φ(token)`。证书在令牌空间定义支撑重叠 `O(A,B) = Supp(A) ∩ Supp(B)`（按 φ 对齐）。跨体迁移只在 `O(A,B)` 上放行，且必须**收缩**（与 v20 P32 同构）：`Θ_n^trans(A→B) = Θ_n^col(A) ∩ O(A,B)`。本体差异大时 `O→∅`，直接退回 v20；**迁移只能收缩，不能扩张**。

## 3. 与基线的接口（如何退化）

- UCW 失效（解码器不可用/令牌越界）⇒ 拒绝执行 ⇒ 退化为 v20 固定证书（更保守）；
- DPL 失效（溯源缺失）⇒ 所有样本按最大重复计权 ⇒ 支撑收缩 ⇒ 等价 v20；
- ACDC 失效（无法主动采集）⇒ 仅用被动数据 ⇒ 证书不扩张 ⇒ 等价 v20；
- CEST 失效（跨体对齐不可用）⇒ 仅单本体证书 ⇒ 等价 v20；
- CCGC 失效（治理失效）⇒ 冻结采集与再认证 ⇒ 等价 v20（安全但停滞）；
- **安全继承**：固定数据快照 `D_k` 下，UCW 只加门不加权，故 `Exec_v21(D_k) ⊆ Exec_v20(D_k)`；跨快照扩张仅经 RB，RB 未通过或分布偏移超阈值则保持 v20 域。

## 4. 预期贡献

1. **令牌级证书封装**：首次把统一机器人基础模型的输出纳入可审计的证书门，给出令牌量化桶的最坏情况放行规则；
2. **数据即见证**：给出采集溯源驱动的证书支撑度量与去重，纠正“数据量 = 覆盖”的错觉，使“没采到”显式变成 UNKNOWN；
3. **主动证书采集**：把主动学习目标从“模型精度”改为“证书保守性最小化”，并给出影子区零碰撞的采集约束；
4. **再认证屏障**：给出跨数据快照的安全扩张条件，调和“采集扩张域”与“安全继承”的张力；
5. **跨体支撑迁移**：用 UniBot-V1 的令牌嵌入把 v20 的跨物体谱系扩展为跨本体支撑重叠，`Exec_v21 ⊆ Exec_v20` 在固定快照与 RB 双重约束下成立。

## 5. 本轮最大风险

**一句话**：主动采集以“证书边界”为采集目标，若再认证屏障的留出探针与采集分布同源（用同一采集策略生成），就会形成**自证循环**——证书在采集流形上看起来覆盖充分、处处 SAFE，而部署一旦偏离采集流形（分布偏移）便发生碰撞；即“越采越自信、越自信越盲”的**覆盖幻觉**。

# IP-425 UniBot Certificate Wrapper
class UniBotCertificateWrapper:
    def __init__(self, unibot, decoder, ccv, quantizer, budget_ms=12.0):
        self.unibot = unibot        # UniBot-V1 基础策略
        self.decoder = decoder      # token -> embodiment theta
        self.ccv = ccv              # v20 证书查询（CCV/CTS/CFC 汇总）
        self.q = quantizer          # 令牌语义量化器
        self.budget_ms = budget_ms

    def propose(self, obs):
        return self.unibot.act(obs)                 # 归一化动作令牌

    def gate(self, tokens, node, obj, embodiment):
        # 1. 令牌量化桶内的最坏参数：保证桶内任一解码都安全才放行
        theta_worst = self.q.worst_case(tokens, embodiment, self.decoder)
        # 2. 证书门：只放行已证域（v20 的 SAFE 结论）
        if not self.ccv.certified(node, obj, theta_worst):
            return None, "TOKEN_GATE_REJECT"
        # 3. 实时预算：门控必须在控制周期内完成，否则保守回退
        if self.estimate_latency(tokens) > self.budget_ms:
            return None, "GATE_TIMEOUT_FALLBACK"
        return self.decoder(tokens, embodiment), "OK"

    def estimate_latency(self, tokens):
        # 与令牌维度线性、与桶内样本数对数相关的经验模型
        return self.q.latency_model(tokens)


# IP-426 Data Provenance Ledger
@dataclass(frozen=True)
class Provenance:
    collector_id: str
    embodiment: str
    object_sig: tuple          # 复用 v20 的 G(o)
    token_bucket: tuple
    env_condition: tuple       # 光照/遮挡/反射
    policy_hash: str           # 采集策略指纹
    timestamp: float

class DataProvenanceLedger:
    def __init__(self, dup_lambda=0.5, tau_s=0.5):
        self.records = []
        self.cell_index = {}    # cell -> list[weight]
        self.dup_lambda = dup_lambda
        self.tau_s = tau_s

    def add(self, sample, prov, cell):
        w = self.effective_weight(prov)
        self.records.append((sample, prov, cell, w))
        self.cell_index.setdefault(cell, []).append(w)
        return w

    def effective_weight(self, prov):
        # provenance 去重：同策略/同环境/同本体的重复采样，边际贡献指数衰减
        sims = [self.prov_similarity(prov, r[1]) for r in self.records]
        rho = max(sims) if sims else 0.0
        return 1.0 / (1.0 + self.dup_lambda * rho)

    def support(self):
        return {c for c, ws in self.cell_index.items()
                if sum(ws) >= self.tau_s}

    def unknown(self, all_cells):
        return set(all_cells) - self.support()

    def prov_similarity(self, a, b):
        # 几何谱系相似度（复用 v20 γ）+ 环境距离 + 策略/本体一致性
        g = spectrum_similarity(a.object_sig, b.object_sig)
        env = math.exp(-euclid(a.env_condition, b.env_condition) ** 2)
        same_policy = 1.0 if a.policy_hash == b.policy_hash else 0.0
        same_body = 1.0 if a.embodiment == b.embodiment else 0.0
        return 0.4 * g + 0.2 * env + 0.25 * same_policy + 0.15 * same_body


# IP-427 Active Certificate Data Collector
class ActiveCertificateDataCollector:
    def __init__(self, cert, ledger, shadow, cost_model):
        self.cert = cert
        self.ledger = ledger
        self.shadow = shadow
        self.cost_model = cost_model

    def acquisition_score(self, cell):
        # 只在证书未知边界上有非零价值
        if cell not in self.cert.unknown_boundary():
            return 0.0
        gain = self.cert.expected_volume_gain(cell)
        cost = self.cost_model(cell) + 1e-6
        risk = 0.0 if self.shadow.contains(cell) else float("inf")
        return gain / (cost * (1.0 + risk))

    def plan(self, k=16):
        candidates = sorted(self.cert.unknown_boundary(),
                            key=self.acquisition_score, reverse=True)
        chosen = []
        for cell in candidates:
            if cell not in self.shadow:
                continue
            if not self.safe_to_collect(cell):
                continue
            chosen.append(cell)
            if len(chosen) >= k:
                break
        return chosen

    def safe_to_collect(self, cell):
        # 采集动作本身必须被 v20 CCV 证明零碰撞，且存在无碰撞退出路径
        return (self.cert.ccv.certified_action(cell)
                and self.shadow.has_retreat(cell))


# IP-428 Cross-Embodiment Support Transfer
class CrossEmbodimentSupportTransfer:
    def __init__(self, embed, gamma_min=0.8):
        self.embed = embed          # φ(token)
        self.gamma_min = gamma_min

    def overlap(self, support_a, support_b):
        cells_a = {self.embed(c) for c in support_a}
        cells_b = {self.embed(c) for c in support_b}
        inter = cells_a & cells_b
        gamma = len(inter) / max(1, min(len(cells_a), len(cells_b)))
        return inter, gamma

    def transfer(self, theta_dom_src, support_a, support_b):
        inter, gamma = self.overlap(support_a, support_b)
        if not inter or gamma < self.gamma_min:
            return None, "SUPPORT_MISMATCH"
        # 只在重叠单元上放行，且收缩（同 v20 P32）
        return theta_dom_src.restrict_to(inter), "OK"


# IP-429 Collection-Certificate Governance Controller
class CollectionCertificateGovernanceController:
    def __init__(self, ledger, cert, drift, tau_shift=0.2, margin=0.01):
        self.ledger = ledger
        self.cert = cert
        self.drift = drift
        self.tau_shift = tau_shift
        self.margin = margin

    def recertify(self, new_cells, independent_probe):
        # 再认证屏障：探针必须独立于采集策略，否则判为污染
        if self.drift.probe_contaminated(independent_probe,
                                         self.ledger.collection_policy()):
            return "PROBE_CONTAMINATED"
        if not self.cert.validate(independent_probe, margin=self.margin):
            return "RECERT_FAILED"
        # 通过后才把新区并入支撑
        self.cert.admit(new_cells)
        return "RECERT_OK"

    def govern(self, plan):
        rho = self.drift.deployment_shift(self.ledger)
        if rho > self.tau_shift:
            # 部署分布偏离采集流形：冻结扩张，回退 v20 固定证书
            return self.cert.freeze_and_fallback_v20(plan), "SHIFT_FREEZE"
        return plan, "OK"

## 2. 推导

**引理 157（令牌门保守性）** UCW 对令牌量化桶 `Q(token)` 取最坏参数 `θ_worst`，且仅当 `certified(θ_worst)` 时放行该桶。由于 `∀θ∈Q(token): θ ⪯ θ_worst`（按碰撞域偏序），`certified(θ_worst) ⇒ certified(θ)`。故令牌门只删动作、不增动作，固定快照下 `Exec_v21(D_k) ⊆ Exec_v20(D_k)`。∎

**引理 158（数据即见证的支撑单调性与去重）** `Supp(C)` 随采集样本增加单调不减（并集只增），但有效权重 `w_i = 1/(1+λ·dup_i)` 使高度相关样本的边际支撑增益 `ΔSupp/ΔN → 0`；未被见证的单元始终在 `UNKNOWN` 中，保守映射为不安全。故证书的 SAFE 断言只覆盖 `Supp(C)`，不会因“样本多”而凭空变大。∎

**引理 159（主动采集的零碰撞与保守收益）** ACDC 的采集函数只在 `∂UNKNOWN(C)` 上非零，且要求 `cell ∈ S_shadow` 与 `certified_action(cell)`；故每次采集动作本身零碰撞且存在退出路径。采集只提供“候选见证”，是否转化为可执行域由 RB 决定，故采集不直接扩张执行域。∎

**引理 160（再认证屏障的跨快照安全）** 设 RB 用独立留出探针 `P_indep` 在新区上验证碰撞率并以保守 margin 判定。若 `probe_contaminated(P_indep, π_collect)` 为真，则拒绝；否则仅当验证通过才 `admit`。故跨快照的域扩张必须满足“独立覆盖证明”，未通过则新区保持 UNKNOWN；安全下界由 v20 证书 + RB 共同保持。∎

**引理 161（跨体支撑迁移保守性）** CEST 仅在 `O(A,B)` 且 `γ ≥ γ_min` 上放行，返回 `Θ_n^trans = Θ_n^col(A) ∩ O(A,B) ⊆ Θ_n^col(A)`；不满足则退回 v20。故跨体迁移只能收缩参数域。∎

**引理 162（v21 整体安全继承）** 固定数据快照下，UCW 只加门（引理 157）、DPL 只收缩支撑（引理 158）、ACDC 不直接扩张（引理 159）、CEST 只收缩（引理 161），故 `Exec_v21(D_k) ⊆ Exec_v20(D_k)`。跨快照扩张仅经 RB（引理 160），RB 未过或 `ρ_shift > τ_shift` 时冻结为 v20。故 v21 的安全下界不弱于 v20。∎

## 6. 已知风险与失效模式

1. **令牌量化桶爆炸**：若 UniBot-V1 的令牌桶过粗，桶内最坏 θ 可能远离标称 θ，导致门控拒绝率过高、活性骤降；过细则最坏 θ 计算代价上升。缓解：自适应桶粒度、增量最坏 θ 维护、分桶缓存。
2. **provenance 去重过强/过弱**：去重过强会丢掉真正的新覆盖，过弱则把相关样本误计为独立覆盖。缓解：按留出验证校准 `dup_lambda`，引入环境/策略/几何多维度相似度。
3. **采集自证循环（核心失效）**：ACDC 专采证书边界，若 RB 的探针也由同一采集策略生成，则“采集→支撑→再认证”闭环自我确认，产生覆盖幻觉。缓解：独立环境探针、独立策略探针、外部审计样本、红队注入。
4. **影子区定义不完整**：`S_shadow` 若高估退出路径（动态障碍、通信延迟），采集动作可能陷入不可退出的状态。缓解：在线可达性校验、保守退出裕度、采集超时中止。
5. **跨体嵌入语义错位**：同一令牌在不同本体上物理含义不同，`φ` 对齐可能把“看起来相同、实际不同”的单元错误重叠。缓解：本体元数据校验、跨体配对留出验证、`O(A,B)` 保守收缩。
6. **分布偏移检测滞后**：`ρ_shift` 基于滑窗统计，部署环境突变时可能滞后。缓解：多尺度滑窗、变化点检测、在线不确定性监控。
7. **采集成本与隐私**：主动采集增加机器人/人工/带宽成本，跨体数据共享带来隐私与合规问题。缓解：成本感知采集、联邦式特征共享（只共享 provenance/支撑统计，不共享原始轨迹）。

## 7. 本轮最大风险

**一句话**：主动采集以“证书边界”为采集目标，若再认证屏障的独立留出探针与采集分布同源（由同一策略生成），则“采集→支撑→再认证”形成**自证循环**——证书在采集流形上处处 SAFE，而部署偏离该流形时发生碰撞，即“越采越自信、越自信越盲”的**覆盖幻觉**。
