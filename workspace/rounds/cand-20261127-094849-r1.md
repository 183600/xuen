## 1. 直觉与动机（两个灵感的碰撞）

### 灵感 1（视觉编码器 → VLM 是「语义学家」，不是「测量仪」）
直觉：现有方案默认把 Qwen-Image 视觉塔当万能眼睛。但三类最易失分任务的失败发生在**毫米与毫秒尺度**：插网线要对准端口、拉拉链要咬住齿、灌药要对准瓶口。预训练的 patch 化与语义对齐恰恰抹掉这些细节；而 4 路相机里真正的「显微镜」是两路腕部相机（F20，原生 480×640），却被大多数队伍当作全局视角的补充。视觉编码器该分工：慢的语义通路回答「做什么、对哪个物体」，快的几何/接触通路回答「贴上了吗、滑了吗、对准了吗」。

严谨定义：设观测为 \((I^g_L, I^g_R, I^w_L, I^w_R, s_t, \ell)\)。把视觉编码拆成两条：
- 语义编码 \(E_{sem}\)：冻结 VLM，输入全局视图，低频；
- 接触带编码 \(E_{geo}\)：小 ViT/DINOv2-patch，输入腕部视图原生分辨率 + 局部光流，高频。
动作头 \(A\) 通过门控 \(g_t\in[0,1]\) 融合：\(h_t = g_t\cdot E_{geo}(wrist_t) + (1-g_t)\cdot E_{sem}(global_t)\)，门控由任务族先验与接触信号共同驱动，两路编码并入**同一 checkpoint / 同一前向图**。可证伪判据：\(E_{geo}\) 的 patch 有效感受野（折算到物理尺寸）必须小于最小操作物特征（拉链齿/针尖/端口），否则该通路形式存在但无信息增益——这可用 L0 探针直接测。

### 灵感 2（多传感器融合 → 「没有触觉」不等于「没有接触感知」）
直觉：赛题删除力/触觉通道，看似封死接触任务；但接触会在别的传感器留下痕迹：夹爪指令在闭合、实测开度却卡住 → 抓到了；末端指令往前走、实测位姿被顶回 → 碰到硬物；腕部画面里物体不随夹爪走 → 滑了。把「指令—实测」的失配与腕部视觉融合，就能凭空造出一路**虚拟力/接触通道**。这不是加硬件，是把已有传感器里被浪费的物理信息榨出来。

严谨定义：时刻 \(t\)，由上一帧指令 \(a_{t-1}\) 与当前本体 \(s_t\) 构造残差特征：
- 任务空间跟踪残差 \(e_t = p_t - \mathrm{FK}(a_{t-1})\)（`ee` 控制时直接用 \(p^{cmd}\)），及其差分 \(\dot e_t\)；
- 夹爪接触裕度 \(m_t=\mathrm{clip}(g^{cmd}_{t-1}-g_t,0,\infty)\)，与闭合停滞指示 \(\mathbb 1[|\Delta g_t|<\varepsilon \wedge \Delta g^{cmd}_t<-\delta]\)；
- 腕部滑移分数 \(slip_t\)：物体跟踪流与夹爪流的不一致度；
- 接触状态 \(z_t=\sigma(\mathrm{MLP}([e_t,\dot e_t,m_t,slip_t,flow\_stats_t]))\in\mathbb R^k\)。
标签**自监督**：用示教里的三类事件自动标注接触起点/失稳段——(i) 夹爪指令持续闭合而实测开度停滞；(ii) 末端实测速度与指令速度反号且幅值突增；(iii) 抓取后物体相对夹爪位移突增。再人工抽检 5%。\(z_t\) 作为额外 token 注入动作头，并复用为 I3 伺服触发与 I5 合成示教的质量门。核心反直觉点：**虚拟力不是物理力的数值近似，而是接触「状态机」的可观测代理——只要它在示教上对接触事件有高 AUC，就足以门控动作。**

### 灵感 3（接口即传感器调度器 → 把 66ms 预算花在刀刃上）
直觉：`obs_delta_indices` 允许选传感器、给每模态单独时间分辨率（F21）。4 路 480×640 图像是带宽/延迟大头，本体状态几乎免费。不同任务该看不同组合：接触任务要腕部高频、全局低频；搬运/摆放要全局中频、本体高频。融合的第二层不是「都接进来」，而是**按任务与延迟预算主动调度**。

严谨定义：观测 schema \(S=\{(key,\Delta_{key})\}\)，代价 \(B(S)\)（每步字节）与延迟 \(L(S)\)（实测 p99）。在 \(L(S)\le 0.8\times 66\text{ms}\) 约束下最大化留出集成功代理。因 `metadata` 是否逐 episode 重读尚未核实，先采用**全局单一 schema + 模型内模态门控**（安全默认）；确认可逐 episode 重读后再上按任务族自适应 schema。这样「融合」同时是精度问题与预算问题。

**三者统一**：前两轮的数据引擎（I1/I2/I5/I9）解决「见得多」，本轮感知融合（I10/I11/I12）解决「看得准、摸得到（虚拟）」。二者相乘：数据决定分布覆盖，感知决定在覆盖内能否跨过毫米级门槛。本轮结论：**接触任务的分数上限由感知的物理精度决定，而不是由数据量决定。**

## 2. 对 v1.1 痛点的增量修订

- P4（无触觉）：从「靠视觉伺服绕过」升级为「用本体-视觉融合重建虚拟接触通道」，难度下调，并与 I3 共用触发信号。
- P2（泛化缺口）新增**表示瓶颈**：外观/背景轴上，语义编码器可能把「新杯子」与「旧杯子」映到同一点，导致动作先验错配；I12 的跨视图自监督针对表示而非数据。
- 新增 P9（感知-延迟耦合）：传感器越多，单步预算越紧；模态子集必须当优化变量，而非全部接入。
- P1/P3/P5/P6/P7/P8 保持。

## 3. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

- **Q9（虚拟力可辨识性）**：15Hz、无力传感器下，本体残差 + 腕部视觉对接触起点/失稳的 AUC 上限是多少？哪些事件标签可靠、哪些是控制器滞后伪影？
- **Q10（双编码器融合的最小充分性）**：腕部接触带编码相对全 VLM 在接触任务上增益多少？门控 \(g_t\) 用什么监督（任务族先验 / 接触信号 / 可学习）？
- **Q11（传感器调度）**：在 p99 ≤ 53ms（0.8×66）约束下，哪些 \((key,\Delta)\) 子集对 32 任务整体最优？全局单一 schema 与逐任务 schema 的收益差多大？

## 4. 设计原则（新增 PR6，其余保留）

- **PR6 可观测性优先**：任何感知模块只能消费 obs 目录里真实存在的通道（F20）；不得假设深度、力、电流或相机外参存在。无外参时禁止显式三角化，改用学习式跨视图一致性。与 PR5 互补：PR5 管数据，PR6 管感知假设。
- **PR7 接触可证伪律**：任何「接触/力」派生量必须先在一组示教上给出可复现的事件 AUC；AUC 不达标即降级为触发信号，不得进入学习表征或作为监督标签。
- PR1–PR5 保留（第 1/2 轮 §4）。

## 6. 本轮最大风险

**一句话**：I10 的虚拟力信号源是 15Hz 顺应控制器上的「指令−实测残差」，极可能被控制滞后与传感器噪声主导；若 L0 接触事件 AUC < 0.75，I10 必须从「进入动作头的学习表征」降级为「仅驱动 I3/I5 的触发门控」，否则会给 I3 的伺服触发与 I5 的合成示教注入伪标签，反而扩大负迁移——所以 I10 是本清单里第一个必须先过 PR7 可证伪闸、再谈融合收益的点。

## 7. 下轮迭代计划（深化与修剪，不推倒）

- **深化**：I10 事件标签管线与 AUC 基线（先在 3 个接触任务上做离线验证）；I11 用实测延迟拟合 \(L(S)\) 代理模型并搜索 schema；I12 最小跨视图对比损失原型（冻结 DINOv2 先跑 kNN 探针）。
- **修剪**：若 I12 的 L0 表示探针无增益，退化为「冻结 DINOv2 + 几何描述词」而不训练新编码器；I7 仍在裁撤观察位。
- **待核实**：`metadata` 是否逐 episode 重读（决定 I11 能否逐任务调度）；`lower_body[15]` 的具体自由度与 pivot 语义；官方是否在任何文档给出相机内外参；是否存在未列入目录的可选深度/IR key。

## 1. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I10 v1 本体-视觉接触融合的虚拟力通道（新） ★★★★
- **动机**：F20 确认无力/触觉/深度，而 6–8 个接触任务（PlugCharger、PlugInEthernet、ZipUp、SyringeWaterTransfer、PourOutMedicine、Unlock…）的失败发生在接触瞬间；纯视觉策略在遮挡与毫米级对准上不可靠（P4）。
- **与现有方案差异**：别队把「无触觉」当既成事实，用更花哨的视觉绕过；本点承认缺失，但从**已有传感器的失配中重建接触**：指令-实测残差、夹爪闭合停滞、腕部滑移共同构成接触状态 \(z_t\)，作为额外 token 进入同一动作头。相当于零硬件补回一路「触觉」。
- **技术可行性**：中。三类事件标签在示教上可直接检测；MLP 估计器 < 1M 参数；在线推理仅多个标量输入，≈0 额外延迟（与动作头同一步）。唯一不确定是信噪比。
- **所需资源**：1×24GB GPU；事件检测与验证 1 人周；无新数据（复用 32 任务 + 110 语料示教）。
- **落地步骤**：①实现三类事件检测器并在 3 个接触任务上算 AUC（PR7 闸）；②若 AUC 达标，训练接触估计器（自监督 + 5% 人工抽检）；③\(z_t\) 以额外 token 注入 DiT 动作头；④在 I3 伺服触发与 I5 段标注中复用；⑤L0：接触任务 Δprog 与失稳恢复率。
- **风险**：15Hz 顺应控制器的残差被滞后/噪声主导（本轮最大风险）；若 AUC<0.75 则降级为纯触发信号。若组委会把辅助估计器视为「第二个模型」，用蒸馏把 \(z_t\) 灌回 VLA（I10'，同 I3' 预案），推理仅保留 VLA。

### I11 v1 多速率多视图传感器 schema 调度（新） ★★★★
- **动机**：F21 允许选键与独立时间栈；F23 把延迟/带宽纳入可信度。4 路 480×640 图像是大头，本体状态近乎免费（P9）。
- **与现有方案差异**：默认方案把所有可用键塞到同一频率；本点把「融合哪些传感器、各以什么频率」当显式优化问题，在 66ms 预算内求解。
- **技术可行性**：高。纯离线 profiling + 组合搜索；`image_resize` 与 `obs_delta_indices` 均为现成接口。
- **所需资源**：无 GPU；1 人 3–5 天（延迟代理模型 + schema 搜索 + 端到端 run_client 验证）。
- **落地步骤**：①测量每个 (key, Δ, resize) 的传输字节与 p99；②拟合 \(L(S)\)；③在 \(L(S)\le53\)ms 下最大化 L0 成功代理，得全局单一 schema；④模型内加模态门控（安全默认）；⑤若确认 metadata 逐 episode 重读，再按任务族细分。
- **风险**：过度精简丢信息（缓解：以 L0 Δprog 为约束，非纯延迟最优）；metadata 重读语义未核实（默认不依赖）。

### I12 v1 跨视图自监督接触带视觉编码器（新） ★★★
- **动机**：外观/背景泛化（P2 轴 3/4）本质是**表示**问题：VLM 语义嵌入可能把不同外观的同类物映到同一点（或把同物不同视角映远）。腕部/全局多视图冗余提供了免费的自监督信号。
- **与现有方案差异**：I1 从数据侧造样本；本点从表示侧用多视图一致性直接训练编码器，使单视图 nuisance（光照、背景、轻微标定漂移）不改变物体-接触相关表征。
- **技术可行性**：中。冻结 DINOv2 + 对比/一致性损失，先做 kNN 线性探针；不训练大 VLM。
- **所需资源**：1–2 GPU 日（32 任务 + DiverseManip 多相机帧）；1 人周。
- **落地步骤**：①构建同刻多视图正样本 / 跨刻负样本；②跨视图 InfoNCE + 单视图扰动一致性（模拟标定漂移）；③冻结编码器 + kNN/线性探针评估外观偏移集；④若增益 >2 点再解冻微调并接 I10/I9。
- **风险**：无外参时跨视图对应不可靠（缓解：用学习式相对位姿/实例级对比而非像素三角化，遵守 PR6）；增益不足则退化为纯冻结 DINOv2 特征，不训练新编码器。

### I3 v3 接触任务族关键点视觉伺服回退 ★★★★（修订，↑）
- 骨架同 v1.0/v1.1：通用 chunk 策略负责接近段、几何伺服负责接触段，同一策略服务内混合推理（PR2 边界待确认，最大前提）；`ee` 控制空间 + per-step 调用天然支持。
- **本轮修订**：伺服触发不再只依赖外置关键点检测（易受外观偏移影响），改用 **I10 虚拟接触 \(z_t\) 的事件信号**作为主触发，关键点仅作门控确认；这样触发在遮挡下更稳（本体残差不需要看见端口）。**降级预案 I3'** 不变。

### I4 v2 人手干预感知门控 + 自适应 chunk ★★★★（修订）

### I5 v3 非标称示教合成 + 得分点对齐恢复 ★★★★（修订）

- **风险**：同 I10——伪标签污染；缓解：PR7 闸 + 只保留能跨过下一得分点的合成段。

### 2.1 虚拟接触特征与自监督标签（I10）

```python
# 在线特征：只吃上一帧指令 + 当前/上一帧本体（F20/F22），零额外传感器
class ContactFeatures:
    def __call__(self, prev_a, s_t, s_prev, wrist_flow):
        p_cmd = prev_a.ee_left if self.space == "ee" else fk(prev_a.left_arm)
        e     = s_t.ee_left - p_cmd                     # 任务空间跟踪残差
        de    = e - self.e_prev; self.e_prev = e
        g_c, g = prev_a.left_gripper, s_t.left_gripper
        m     = max(0.0, g_c - g)                       # 夹爪接触裕度
        stall = float(abs(g - s_prev.left_gripper) < EPS and (g_c - s_prev.left_gripper) < -DELTA)
        slip  = flow_dissim(wrist_flow, gripper_flow(wrist_flow))  # 物体流 vs 夹爪流
        return concat([e, de, [m, stall, slip], flow_stats(wrist_flow)])

class ContactEstimator:                                  # <1M 参数，输出接触状态 z_t
    def forward(self, feat): return torch.sigmoid(self.mlp(feat))  # [grasp, contact, slip, ...]

# 离线自监督标签（用示教对齐帧，PR7 闸：先测 AUC 再上线）
def pseudo_contact_labels(ep):
    grasp   = detect_plateau(ep.gripper_cmd, ep.gripper_state, EPS, DELTA)   # 指令闭合但实测停滞
    contact = detect_opposite_motion(ep.ee_cmd, ep.ee_state)                # 实测速度与指令反号突增
    slip    = detect_relative_slip(ep.wrist_flow, ep.ee_state)              # 抓后物体相对夹爪位移
    return {"grasp": grasp, "contact": contact, "slip": slip}
```

### 2.2 双通路融合进单一动作头（I10 + I12，PR2：同一 checkpoint）

```python
class FusedVLAPolicy:                                    # 唯一参赛实体：一个 PolicyService
    def get_action(self, obs):
        z  = self.contact(ContactFeatures()(self.prev_a, obs.state, self.prev_s, obs.wrist_flow))
        h  = self.sem_encoder(obs.global_views)          # 冻结 VLM，低频（可隔帧）
        w  = self.geo_encoder(obs.wrist_views, obs.wrist_flow)  # 接触带，高频（I12 训练）
        g  = self.modality_gate(h, w, z)                 # 门控 ∈ [0,1]
        tok = torch.cat([(1 - g) * h, g * w, z.unsqueeze(1)], dim=1)
        self.prev_a, self.prev_s = self.last_action, obs.state
        return self.action_head(tok)                     # DiT 输出 action chunk
```

### 2.3 传感器 schema 搜索（I11）

```python
def schema_cost(S, bytes_model, latency_model):
    return sum(bytes_model(k, d) for k, d in S), latency_model(S)   # 每步字节 / p99

def search_schema(cands, heldout):
    best = None
    for S in cands:                                  # 键子集 × 每键 stride × resize 的组合
        B, L = schema_cost(S, bytes_model, latency_model)
        if L >= 0.8 * 66: continue                  # F12：单步预算 ≈66ms，留 20% 余量
        score = l0_success_proxy(S, heldout)        # L0 代理，不是纯延迟最优
        if best is None or score > best[0]: best = (score, S)
    return best[1]
# 安全默认：全局单一 schema；确认 metadata 可逐 episode 重读后，再按任务族细分
```

### 2.4 跨视图自监督（I12）

```python
def cross_view_loss(geo, b):                         # 无外参：学习式一致性，不做像素三角化（PR6）
    zL, zR, zW = geo(b.left_high), geo(b.right_high), geo(b.left_wrist)
    L_inst = infonce(zL, zR) + infonce(zR, zW)        # 同刻同场景为正，跨刻为负
    L_inv  = mse(norm(geo(aug_calib(b.left_high))), norm(zL))  # 模拟标定漂移/光照
    return L_inst + 0.5 * L_inv
```

## 3. 实验设计（v2 分级消融协议 + 感知侧闸门）

| 级别/闸门 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| G1 接触可辨识（PR7） | 3 个接触任务上算 grasp/contact/slip 事件 AUC | 离线（免费） | grasp AUC>0.80；contact/slip>0.75；否则 I10 降级为触发信号 |
| G2 不伤标称 | 加 \(z_t\) 前后标称集 Δprog | 离线 | 标称 Δprog ≥ 0（允许门控自动关小） |
