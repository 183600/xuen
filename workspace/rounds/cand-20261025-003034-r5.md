# 第 8 轮 · SEAM：技能不是瓶颈，接缝才是；联邦是接缝的数据工厂

> 检索/复核日期：**2026-10-25（UTC）**。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。状态文件已到第 7 轮（PILOT-GPR），本轮按第 8 轮续写；用户口径的“第 5 轮”与文件轮次不一致，以文件为准。本轮三个灵感词是「技能组合」「联邦学习」「产学研合作」。我先各自钉到本轮核实到的官方事实与 2026 年新证据上，再合成主判断：**32 个任务不是 32 个整体，而是 94 个技能段和 62 个接缝；终局放置只是权重最高的一条接缝。真正该攻的是接缝处的“下一技能就绪”问题：用 predecessor-terminal-state 训练、专用 handoff 专家、接缝合同/门控与接缝检索/恢复，把 62 条接缝逐一变成可检查、可修复的接口；用联邦技能工厂让实验室成为接缝数据发生器；最终蒸馏回一个稠密 checkpoint，守住单模型与低延迟。** 第 7 轮的放置工作不丢，但从“唯一目标”降为“最高优先级的接缝”。

## 0. 本轮先核实：八个会改变策略的事实

### 0.1 排名是“成功率优先，步骤分只做 tie-break”

Feishu 参赛手册（中文 [S1]、英文 [S2]）明确：实时榜单按 32 个任务的 **总平均成功率** 排序；成功率相同才看 **总平均步骤分**；仍相同则提交日期较早者靠前。网站首页仍写“按平均成功率与步骤分综合排序” [S3]，但手册的 lexicographic 规则更具体，应以手册为准。

这修正了第 7 轮的一个倾向：第 7 轮把“终局步骤占 39.8%、放置类步骤约 59.7%”当作“步骤分大头”的主目标。现在必须改成：

```text
主目标 = P(全部步骤完成) = 成功率
辅助   = E[步骤分]（只在成功率打平时决定名次）
训练   = 步骤分可以作为稠密信号，但不能为了步骤分牺牲终局成功
```

**步骤分是训练信号和 tie-break，不是主目标。** 任何“刷步骤分”的策略（做易步骤、停在半路、假完成）都必须被终局闸门压住。

### 0.2 每个任务 10 次，5 类泛化各 2 次；单次 180 秒

手册 [S1][S2]：每个任务执行 10 次独立运行，包含 5 种泛化类型（位置、干扰物、桌面背景、未见物品、人为干扰），每种各出现 2 次；单次真机执行最大允许 180 秒，超时记失败。32×10=320 个计分 episode。

统计含义：每个泛化轴只有 2 次/任务，单任务噪声很大；必须用配对设计、跨任务聚合、bootstrap 置信区间，不能根据单个任务的小波动下结论。320 trials、p≈0.3 时 SE≈2.56pp，**+2pp 级别的差异基本不可分辨，目标应放在 +5pp 以上或机制性改进**。

### 0.3 32 个任务 = 94 个技能段 + 62 个接缝；终局步骤在 32/32 任务里都是最高权重

我把 32 个 `tasks_v2/<slug>/info.json` 的 `score_steps` 全量抓下并聚合 [S4]：

- 总步骤数 **94**，总接缝数 **62**（每个任务 K 步有 K−1 个接缝）。
- 任务长度：2 步 11 个、3 步 14 个、4 步 5 个、5 步 2 个；所以接缝数分别为 1、2、3、4。
- 终局步骤合计 **1275/3200 = 39.8%**；并且在 **32/32** 个任务里，终局步骤都是最高权重（18 个任务并列最高）。
- 终局动作分类：place/put/hang/stack/return/store/pack 16 个；close/zip/lock 7 个；insert/plug 2 个；pour 1 个；remove/unplug/pick-out 2 个；straighten/flip/fold/inject 4 个。**28/32 的终局是“放置/闭合/插入/倾倒/取出”类终局操作**，只有 4 个是摆正/翻转/折叠/注射。
- 最短 2 步（T01/T02/T03/T05/T08/T14/T19/T23/T24/T30/T32），最长 5 步（T16/T17）；接缝最多的任务有 4 条接缝。

这比第 7 轮“终局放置是闸门”更精确：**终局放置是权重最高的一条接缝，不是唯一的接缝；62 条接缝都要过。**

### 0.4 榜单仍是占位，不能分析“真实头部方案”

本轮实测 [S5][S6][S7]：

- `leaderboard.html` 仍是「即将发布 / Coming Soon」；`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`。
- 8 个模型（MolmoAct2 29.7/39.0、WALL-OSS-0.5 28.5/38.9、DreamZero 27.9/37.9、Spirit-v1.5 25.9/34.4、DM0 23.5/31.7、PI-0.5 22.8/30.6、GigaBrain-0 22.6/29.5、GR00T N1.5 20.5/28.1）是脚本生成的占位数据。
- `runs.html` 也是 256/256 占位，详情页明确写“视频占位”。

**用户说的“榜首成功率也不到 30%”来自占位数据，不是真实团队。** 我们不能从这些数字推断谁强谁弱，也不能推断真实头部方案的做法。唯一可谨慎使用的量：8 个占位模型的“步骤分 − 成功率”平均约 +8.6pp（最高 +9.3pp），这与“多数失败发生在做完大部分步骤、倒在最后一步/最后一条接缝”一致；但这只是弱先验，必须标“未核实”。

### 0.5 数据规模：挑战集 33,276 条 / 169h；辅助集 29,892 条 / 174h；合计约 63k / 343h

本轮从 HF collection 的 `lerobot.totalEpisodes` 与 `numRows` 聚合 [S8][S9]：

| 集合 | 数据集数 | episodes | frames | 约小时（30fps） | 许可 |
|---|---:|---:|---:|---:|---|
| UniBot-V1 Challenge Dataset | 32 | 33,276 | 18,282,246 | 169.3h | 见各数据集 |
| UnifoLM_G1_Dex1_Dataset | 72 | 29,892 | 18,834,191 | 174.4h | 多为 Apache-2.0 |
| 合计 | 104 | 63,168 | 37,116,437 | 343.7h | 需逐集核对 |

挑战集每个任务 969–1,533 条；HangCup 1,043 条 / 194,564 帧 / 30fps / LeRobot v3.0 / `robot_type=unitree_g1` / Apache-2.0；四路相机 `head_stereo_left/right` + `wrist_left/right`，EE 位姿有 base 与 torso 两套；**数据没有 subtask/skill 标签列**。

指令方面：挑战集 `meta/tasks.parquet` 每任务 **5 条英文复述**（`@` 分隔），本轮用 pyarrow 复核 HangCup 与 Unzip 均成立 [S10]；辅助集 `G1_Dex1_Assembling_Motor` 的 `tasks.parquet` 有 **20 条指令变体**（0–19 行），是语言泛化的额外数据。

按挑战集平均 2.94 步切段，约 **97.8k 个技能段**；加辅助集按 4 步估约 **+120k**，合计约 **21–22 万技能段**，量级与 Behavior-Skill 的 235,492 个技能实例相当 [S11]。这是“技能专家库”而不是“任务级微调”的数据基础。

### 0.6 WLA-1.0-Base 给了单 checkpoint 的物理底座

UnifoLM-WLA-1.0-Base [S12]：6B 参数、约 2,500 小时真机数据、64 个任务、支持两指夹爪与五指手；2026-09-28 发布 base + 微调代码；VLM backbone 冻结，action expert/projector 可训练；默认单张 24GB GPU；支持 `trainer.lora` 配置（qwen_vl_interface 的 `q_proj/k_proj/v_proj/o_proj`，action expert 的 `to_q/to_k/to_v/to_out.0/add_q_proj/add_k_proj/add_v_proj/to_add_out`）；模型服务 websocket/msgpack，**Dex1 only** 动作空间 [S13]。

这意味着：**技能专家可以是同一 6B 底座上的多组 LoRA，而不是多套模型；训练可以单卡 24GB 逐个专家进行；推理可以在一个 checkpoint 内合并/路由。** 单模型合规有物理可行的实现路径。

### 0.7 2026 年的新证据：接缝是独立于“技能能力”的失败源

本轮重点复核了五篇直接相关的 2026 年论文：

- **OSS（Observation-Space Shift）** [S14]：在 BOSS-44 的三技能链上，链式成功率从执行完第一项技能后的 **88.5%**，掉到两项后的 **34.3%**（一条接缝），再掉到三项后的 **7.6%**（两条接缝）；主导偏移来自**被前序技能移动的场景状态**（打开的抽屉、被留在旁边的物体），不是机器人关节构型或下游要操作的物体本身。用“检测 stall → 恢复场景 → seam-robust fine-tuning”把全链成功率从 **7.6% 提到 26.5%**（3.5×，达到特权恢复 oracle 的 51%）。
- **Baton（Don't Drop the BATON）** [S15]：长程操作里 VLA 的 primitive 有 exit condition 但没有 entry condition；子任务可以“成功”成后继无法使用的形态。Baton 用 transition-aware memory 显式记录 **invocation / handoff / lookahead** 三种转移，在 RoboMemArena 上相对 SoTA 大幅提升。它的结论是：**边界是对象，不是节点**；entry condition 是“这一对技能”的事实。
- **Semantic Handoff Failures** [S16]：在 BEHAVIOR-1K 上，同一个 π0.5 技能 checkpoint 从干净边界快照启动时，导航/抓取/放置/开门等技能有 **77–100%** 成功率；但从链式终态启动时，组合 rollout 仍频繁卡住。失败被归因到 next-skill readiness、target grounding、control execution。
- **Behavior-Skill** [S11]：235,492 个技能实例、10,000 条演示、50 个家务任务、34 个技能类；失败在不同技能间高度不均匀，接触丰富技能是持续瓶颈。**任务级汇总会掩盖中间失败。**
- **ManiUnit** [S17]：137,899 个技能段、21 个技能类型、417 个子任务；技能策略在局部操作上 **78.7%**，任务策略只有 **49.3%**；但完整任务仍只有 **4.0%**，加规划器才到 **18.0%**；关节构型扰动让全 benchmark 成功率下降约 **56%**。**技能学会了，不等于接缝会接。**

这五篇合起来给出一个很锋利的判断：**技能能力与接缝能力是两种能力；只练技能，会把失败推迟到接缝；只攻终局放置，会把失败留在前 61 条接缝。** 第 7 轮的放置工作是对最后一条接缝的专项优化，方向对，但覆盖面不够。

### 0.8 2026 年的联邦证据：不是隐私表演，是“异构适配器装配”

- **RoboFL / MoSAIC** [S18]：把各客户端本地训练的 LoRA 直接装成 server MoE 的专家分支，server router 学 token 分配；在 Franka 真机上比集中式 PEFT InternVLA-A1 **+12.23%**，每轮客户端通信最多降 **86.81%**。
- **Co-VLA** [S19]：用 ADMM 共识优化做联邦 VLA，全模型与参数高效微调都支持，性能**接近集中式**。
- **Federated VLA 实证** [S20]：在 LIBERO 40 任务 + 6 个真机任务、2–3 个站点上系统比较；结论是 **federated scope 比聚合算法更主导**，真机跨站点异构下很难 match 集中式。
- **ForgeVLA** [S21]：无语言标注的联邦 VLA，用 embodied instruction classifier 补语言、对比规划损失防特征坍缩。
- **FedVLA** [S22]：单轮联邦模仿学习，适合“只能通信一次”的极端场景。

这些结果说明：**联邦的价值不只是“数据不出域”，而是“把异构技能适配器装配起来，并让 router 在服务端学组合”。** 对 UniBot，32 个任务本身就是异构的；先做“官方数据上的虚拟联邦”（按任务/技能族分客户端），再做“真实实验室联邦”（接缝状态多样性），是合规且可证伪的路径。

## 1. 三个灵感词，各自钉到官方事实上

### 1.1 技能组合：不是“把任务拆碎”，是“把接缝显式化”

“技能组合”很容易被理解成“把任务拆成技能，再让模型按顺序调用”。这当然对，但不够。UniBot 的 32 个任务已经是显式多阶段（2–5 步），官方评分步骤已经把“技能清单”给了我们；真正缺的不是分解，而是**接缝的表示**：

- 每个技能节点有 pre/postcondition，但**接缝没有 entry condition**（Baton 的核心观察）。
- 每个任务的终局是成功闸门，但**前 61 条接缝没有评分**；失败在哪里发生，任务级指标看不见。
- 技能级训练能提高局部成功率（ManiUnit 78.7% vs 49.3%），但完整任务仍可能只有 4.0%；**接缝是独立乘数**。

一个玩具算术（不是 UniBot 实测，只说明杠杆方向）：

| 链长 | 基线（p=0.8, h=0.8） | 只把终局技能 +10pp | 把全部接缝 +10pp |
|---|---:|---:|---:|
| 2 步（1 接缝） | 51.2% | 57.6%（+6.4pp） | 57.6%（+6.4pp） |
| 3 步（2 接缝） | 32.8% | 36.9%（+4.1pp） | 41.5%（+8.7pp） |
| 5 步（4 接缝） | 13.4% | 15.1%（+1.7pp） | 21.5%（+8.1pp） |

在 3 步任务上，接缝机制的杠杆约是“只攻终局技能”的 **2.1×**；在 5 步任务上约 **4.8×**。这还没有算“终局失败会丢掉全部成功”的非线性。**终局接缝仍然要第一个攻（它权重最高、是成功闸门），但通用接缝机制覆盖 62 条接缝，是更大的杠杆。**

技能组合的第二个含义是**数据组合**：挑战集按平均 2.94 步可切出约 97.8k 个技能段；辅助集再加约 120k。每个技能段都有“前序终态”和“后继初态”，这正是 OSS 说的 chained state。**我们不需要先造一个新仿真器；33k 条全任务演示本身就包含 62 条接缝的 33k 个自然变体。** 这是本轮最重要的可行性判断。

技能组合的第三个含义是**专家组合**：SMoDP [S23] 用语义技能预测器路由 action chunk，参数效率与组合迁移都更好；MoE VLA [S24] 发现简单的 MoE action head 可以让专家复用、性能 match 单体 baseline；SCE [S25] 用“执行专家 + 转移专家”双分支处理技能组合与持续学习。这些结果支持“技能专家 + 转移专家”的结构，但也提醒：**MoE 本身不一定涨点，涨点来自接缝专家和接缝数据。**

### 1.2 联邦学习：不是隐私表演，是“接缝数据工厂”

联邦学习在机器人里的常见叙事是“数据不出实验室”。这对产学研合作很重要，但对竞赛选手还有一层更硬的价值：**接缝状态是异构的，而集中式数据往往只覆盖一个采集环境。**

OSS 的关键发现是：接缝失败的主导偏移是“被前序技能移动的场景状态”，不是机器人关节。不同实验室的桌面布局、背景、容器位置、人的干扰方式，恰好会生成不同的“前序残留”。**每个实验室都是一个接缝状态发生器；联邦是把这些接缝状态聚合起来，而不移动原始数据的最自然方式。**

具体到 UniBot：

1. **官方数据上的虚拟联邦**：把 32 个任务按技能族/难度分成 4 个虚拟客户端（例如放置/堆叠、开合/拉链、插入/双手、折叠/倾倒），每个客户端只本地训练自己技能族的 LoRA 专家；server 用 FedAvg/Co-VLA/RoboFL 装配成 MoLE，再在官方链式状态上训练 router/gate。这**只用官方数据**，完全合规，却能验证“联邦装配是否优于集中式多任务训练”。
2. **真实实验室联邦**：如果规则允许外部自采数据，2–3 个有 G1/Dex1 的实验室各贡献 1–2 个技能族的 LoRA + 接缝状态清单；原始数据不出实验室。server 装配、蒸馏、回发。这是“产学研”从数据农场升级为技能联邦的关键一步。
3. **单轮/少轮**：RoboFL 与 FedVLA 说明 LoRA 适配器可以在 1–2 轮内装配；不需要长期联合训练。比赛周期内可行。

联邦的产出不是一个“更大的模型”，而是一个**可复用的技能适配器协议 + 接缝状态格式**：每个实验室按同一 schema 交 LoRA（rank、target modules、训练数据 hash）和接缝清单（前序技能、后继技能、entry condition、成功/失败、修复动作），server 负责装配与蒸馏。这个协议本身可以赛后开源，成为“产学研”的公共品。

### 1.3 产学研合作：从“数据农场”到“技能联邦”

第 7 轮把产学研定位为“数据农场 + 方法供给 + 验证回路”，这是对的，但还不够。宇树自己的生态已经在做产学研（第 7 轮核实的公开报道 [S26]，本轮未逐条复核）：青岛城市学院产业学院、河南理工大学具身智能学院、柳州城市职业学院、厦门工学院、香港大学上海智能计算研究院、武汉大学数智教育通关实验室、重庆大渡口人形机器人数据采集中心等；高校侧也有成熟的 G1 遥操作/采集/LeRobot 部署流水线。辅助集 72 个数据集、29,892 条、174h、多个 Apache-2.0，就是“生态能产数据”的现成证据 [S9]。

但“数据农场”有一个结构性浪费：**每个实验室都在采完整任务，而真正稀缺的是接缝状态和失败恢复片段。** 一条完整演示里，接缝只占几秒；采 1,000 条完整任务，等于采 1,000 个接缝样本，但也等于 1,000 条重复的技能执行。技能联邦的协议应该反过来：

- 实验室按**技能族**采数据，而不是按完整任务采；一条数据只标注“前序终态 + 后继初态 + 接缝合同”，技能段可以复用。
- 实验室按**接缝**做压力测试：人为制造“前序成功但后继无法启动”的状态（物体被移动、夹爪姿态不对、容器被挡住），记录修复动作。
- 实验室按**适配器**交付，而不是按原始视频交付；原始数据留在本地，只有 LoRA 与接缝清单上云。

三方角色因此更清晰：

| 角色 | 提供 | 得到 |
|---|---|---|
| 宇树（产业） | WLA 底座、官方 32 任务数据、真机评测槽、硬件 | 更鲁棒的参赛模型、技能/接缝 benchmark、生态数据协议 |
| 高校/实验室（学术） | 技能族数据、接缝状态、失败恢复、人工标注、方法复现 | 可发表的 benchmark/协议、算力/数据互补、联合署名 |
| 我们（研究/集成） | 架构、router/gate、MoLE 装配、蒸馏、竞赛提交 | 竞赛成绩、论文、可复用工具链 |

一句话：**产学研在 UniBot 里不是“找几个实验室挂名”，而是把“接缝状态”变成可交付、可组合、可署名的公共品；联邦是它的传输协议，技能专家是它的交付单元。**

## 2. 本轮主判断：从“攻终局放置”升级为“攻 62 条接缝”，终局放置是第一优先级

### 2.1 一个更锋利的失败模型

把任务 t 看成技能链 \(S_1 \to S_2 \to \dots \to S_K\)。每个技能有执行成功率 \(p_i\)，每条接缝有交接成功率 \(h_j\)。任务成功率近似：

```text
P(success | t) ≈ ∏_{i=1..K} p_i × ∏_{j=1..K-1} h_j
```

接缝失败不是“技能没学会”，而是下一技能从一个**训练分布之外的初态**启动。OSS 把它叫 Observation-Space Shift；Baton 把它叫 missing entry condition；Semantic Handoff 把它拆成 next-skill readiness / target grounding / control execution。对 UniBot，我把它拆成五类：

| # | 接缝失败模式 | UniBot 例子 | 对策 |
|---|---|---|---|
| H1 | 前序残留：夹爪姿态/开度不对，物体被留在错误位置 | T27 叠完碗 2 后，夹爪仍朝下、碗 2 偏左 | handoff gate + reset 原语 |
| H2 | 下一技能目标未就绪：容器没开、拉链没对齐、插排没固定 | T31 拉开拉链后，下一技能要伸进笔袋 | entry condition + 容器位姿校验 |
| H3 | 目标 grounding 漂移：下一技能看错物体/槽位 | T06 放完红块后，绿块/中位被遮挡 | 接缝检索 + 关系键 |
| H4 | 控制切换抖动：前一技能的速度/力控未归零 | T10 抓插排后直接抓插头，双臂争抢 | 交接窗口 + 速度/力归零 |
| H5 | 人类 undo：前序完成后被手动撤销 | T27 叠好第二个又被拿掉；T19 拉上又拉开 | Φ 下降检测 + 恢复库 |

### 2.2 为什么这比“只攻终局放置”更该做

第 7 轮的放置论证仍然成立：终局步骤是 32/32 的成功闸门，权重最高，跨五轴同时起作用。但第 8 轮要补三个缺口：

1. **终局只是最后一条接缝。** 62 条接缝里，前 61 条失败会让模型根本到不了终局；只优化终局，等于给一条已经很难到达的路径换最后一公里。
2. **终局放置的失败，很多是接缝失败。** 例如“拿着物体接近容器”是 transport→place 的接缝；“放下后没放稳”是 place→release 的接缝。把放置拆成“接近接缝 + 释放技能 + 落点校验”，比把放置当黑盒更可诊断。
3. **接缝机制可复用。** handoff gate、entry condition、predecessor-terminal-state 训练、seam retrieval 对 62 条接缝都有效；终局专用 PGL/OPT/SVL 只对放置类终局有效。

所以本轮的主判断是：

```text
SAS-MoLE = 单一 WLA-1.0-Base checkpoint
         + Seam Graph（94 技能 + 62 接缝 + 合同）
         + 技能 LoRA 专家库（按技能族）
         + 专用 Handoff Expert（接缝修复）
         + Handoff Gate（entry condition 检查）
         + Seam Retrieval（从前序终态检索下一技能）
         + Chained-State Augmentation（用演示的前序终态训练下一技能）
         + Placement Seam Toolkit（PGL/OPT/SVL，终局接缝特化）
         + Federated Skill Factory（官方虚拟联邦 + 真实实验室联邦）
         + MoLE→Dense Distillation（最终单稠密 checkpoint）
```

## 4. 风险与合规（先立后破）

- **单模型边界**：MoLE 在训练期是“一个 checkpoint + 多组 LoRA 专家”，推理期优先**蒸馏成单一稠密 adapter**；技能 token 是输入条件，不是第二个模型。若官方认定 MoLE 不是单模型，回退到“技能 token 条件化的稠密模型”。模型卡写清。
- **外部数据**：官方 32 任务数据是默认训练集；辅助 72 数据集虽多为 Apache-2.0，但竞赛规则未读全，默认 **OFF**；真实实验室联邦默认 **OFF**，邮件确认后再开。官方虚拟联邦只用官方数据，不受此限。
- **接缝标签**：数据没有 subtask 标签；用“语言步骤顺序 + 视觉变化点检测 + 少量人工标注（5 任务 × 5 视频）+ 几何谓词”生成弱标签；人工标注一致性目标 κ≥0.8；不追求 94 个技能全精标。
- **handoff 数据稀缺**：62 条接缝 × 每任务约 1k 条演示 ≈ 62k 个自然接缝样本；再加失败恢复片段。先训“前序终态 → 后继动作”，再训“异常终态 → 修复”。
- **MoLE 路由坍缩**：用 schedule-first（任务步骤已知）做先验，router 只做 chunk-level 选择；load balance + entropy 正则；top-1 为主，top-2 消融。
- **蒸馏损失**：用 router logits + 动作 MSE/flow loss + 接缝窗口加权；若全任务成功率掉 >2pp，保留 MoLE 并做合规复核。
- **联邦异构**：先做官方任务分区虚拟联邦；真实实验室只做 1–2 轮 LoRA；跨站点差异过大时，按技能族 personalization，不强行 FedAvg。
- **延迟**：技能 token 条件化的稠密模型最稳；MoLE 只在训练/离线用。推理 p99 必须进预算；chunk-level 切换，不做 token-level 高频切换。
- **评测噪声**：320 episodes、SE≈2.56pp；+2pp 不下结论；调试槽只做 go/no-go，不做精细调参。
- **规则未读部分**：手册在 2.2 后截断；截止日期、提交次数、调试槽费用、外部数据政策均未核实；所有“允许”都写成“待确认”。

## 5. 一句话押注

**把 32 个任务看成 94 个技能段与 62 条接缝：用“接缝合同 + predecessor-terminal-state 训练 + 专用 handoff 专家 + 接缝检索/恢复”去攻接缝成功率；终局放置只是权重最高的一条接缝，MoLE/联邦/蒸馏是让它在单 checkpoint 内可训练、可扩展、可合规的载体。**

## 1. 事实核对（本轮新增/修正；来源表见 §10）

### 1.1 排名规则：成功率优先，步骤分只做 tie-break

官方参赛手册 [S1][S2]：

> 实时榜单按 32 个任务的 **总平均成功率** 进行排序，成功率相同时按 **总平均步骤分** 排序，若仍相同，则提交日期较早的模型排序靠前。

网站首页仍写“按平均成功率与步骤分综合排序” [S3]，但手册的 lexicographic 规则更具体，应以手册为准。这是本轮最重要的策略修正：

```text
主目标 = P(全部步骤完成) = 成功率
辅助   = E[步骤分]（只在成功率打平时决定名次）
训练   = 步骤分可作为稠密信号，但不能为了步骤分牺牲终局成功
```

### 1.2 每个任务 10 次，5 类泛化各 2 次；单次 180 秒

手册 [S1][S2]：

- 每个任务执行 10 次独立运行；
- 5 种泛化类型（位置、干扰物、桌面背景、未见物品、人为干扰）各出现 2 次；
- 单次真机执行最大 180 秒，超时记失败；
- 32×10=320 个计分 episode。

统计含义：每个泛化轴只有 2 次/任务，单任务噪声大；必须跨任务聚合、配对设计、bootstrap CI。不要根据单个任务的小波动下结论。320 trials、p≈0.3 时 SE≈2.56pp；+2pp 基本不可分辨，目标 +5pp 以上。

### 1.3 32 个任务 = 94 个技能段 + 62 条接缝；终局步骤 32/32 最高权重

## 2. 接缝的算术：为什么 62 条接缝比一个终局更值得攻

### 2.1 链式成功模型

对任务 t，技能链 \(S_1 \to \dots \to S_K\)，执行成功率 \(p_i\)，接缝成功率 \(h_j\)：

```text
P(success | t) ≈ ∏_{i=1..K} p_i × ∏_{j=1..K-1} h_j
log P = Σ log p_i + Σ log h_j
```

这个模型是近似：技能之间不独立，接缝失败可能导致重试；但它足以说明**接缝是乘数**。62 条接缝意味着 62 个乘数；每一条掉 10pp，整链掉很多。

### 2.2 玩具算术（不是 UniBot 实测）

| 链长 | 基线（p=0.8, h=0.8） | 只把终局技能 +10pp | 把全部接缝 +10pp | 接缝杠杆 |
|---|---:|---:|---:|---:|
| 2 步（1 接缝） | 51.2% | 57.6%（+6.4pp） | 57.6%（+6.4pp） | 1.0× |
| 3 步（2 接缝） | 32.8% | 36.9%（+4.1pp） | 41.5%（+8.7pp） | 2.1× |
| 5 步（4 接缝） | 13.4% | 15.1%（+1.7pp） | 21.5%（+8.1pp） | 4.8× |

读法：

- 2 步任务里，终局技能就是最后一条接缝，两者等价。
- 3 步及以上，**通用接缝机制**的杠杆明显大于“只攻终局技能”。
- 5 步任务（T16/T17）里，接缝杠杆约 4.8×；这两项任务恰好也是 4 条接缝、评分权重最低（每步 20/25），但失败代价是整任务失败。
- 如果终局技能本身 p 很低（例如 0.5），只攻终局的收益会变大；所以**终局接缝仍是第一优先级**，只是不该是唯一。

### 2.3 终局接缝为什么特殊

终局步骤在 32/32 任务里都是最高权重，且是成功闸门；终局动作 28/32 是放置/闭合/插入/倾倒/取出类。终局接缝同时满足：

1. **成功闸门**：不过终局，任务失败。
2. **最大单项权重**：步骤分 tie-break 时，终局分最高。
3. **跨五轴**：位置/干扰物/背景/未见物品/人为干扰都会影响终局。
4. **前序残留的汇聚点**：前 1–4 条接缝的误差会在终局放大（物体姿态、容器位置、夹爪姿态）。

所以终局接缝是第一优先级；但它的失败可能根因在前面的接缝。**SAS-MoLE 的做法是：终局用 Placement Seam Toolkit 特化，前面用通用 Handoff Gate/Expert 兜底；诊断时先看接缝日志，再看终局。**

### 2.4 统计功效

- 320 episodes；p≈0.3 时 SE≈2.56pp。
- +5pp 约 90% 概率排名更高；+2pp 基本不可分辨。
- 每个泛化轴只有 2 次/任务；轴级结论必须跨 32 任务聚合。
- 用配对 bootstrap（同任务、同轴、同初始条件）降低方差。
- 训练至少 3 seeds；检索/蒸馏至少 3 seeds；报告均值 ± 95% CI。

### 2.5 预算分配（修订第 7 轮）

| 方向 | 第 7 轮 | 第 8 轮 | 理由 |
|---|---:|---:|---|
| 终局放置/终局接缝 | 50% | 25% | 第一优先级，但不再是唯一 |
| 通用接缝/handoff/gate | 0% | 30% | 62 条接缝的乘数杠杆 |
| 技能专家/技能段数据 | 10% | 20% | 97.8k 技能段，单卡可训 |
| 联邦/产学研 | 15% | 10% | 先官方虚拟联邦，真实联邦看规则 |
| 工程/部署/调试 | 15% | 10% | FLEET 降为检查单 |
| 评测/分析 | 10% | 5% | SDP 自动化 |

### 3.4 62 条接缝的用途

- **训练**：每条接缝切出“前序终态 → 后继动作”的段，作为 handoff expert 的正样本；再切“异常终态 → 修复”作为负样本/恢复样本。
- **推理**：每条接缝的 entry condition 由 gate 检查；不满足则调用 handoff expert。
- **诊断**：调试槽里记录每条接缝的通过/失败，定位是“技能不行”还是“接缝不行”。
- **联邦**：接缝清单是实验室之间可交换的最小单元；不含原始视频，只含状态谓词、结果、修复动作。

## 4. SAS-MoLE 架构

### 4.1 总览

```text
instruction (5 paraphrases)
        │
        ▼
task match → Seam Graph (94 skills / 62 seams)
        │
        ▼
skill scheduler (k=1..K) ──► Handoff Gate (entry condition)
        │                         │
        │                    not ready
        │                         ▼
        │                  Handoff Expert (reset/reorient/re-stage/regrasp)
        │                         │
        ▼                         ▼
WLA-1.0-Base (single checkpoint)
  ├─ shared action expert (always on)
  ├─ skill LoRA bank (F1..F9, chunk-level top-1)
  └─ handoff LoRA (HANDOFF token)
        │
        ▼
action chunk → env.step
        │
        ├─ skill postcondition verifier
        ├─ Seam Retrieval (predecessor terminal state)
        ├─ Placement Seam Toolkit (PGL/OPT/SVL)
        └─ SRB (undo/recovery)
```

### 4.2 Seam Graph（SG）

**输入**：32 个 `info.json` 的 `score_steps` + 5 条复述 + `generalization` 备注 + 数据 `meta`。

**构建**：

1. 任务识别：指令 → 任务 ID；用 5 条复述的嵌入最近邻 + 关键词规则；覆盖 160 条英文 + 中文映射。
2. 技能节点：每个 `score_step` 一个节点；权重、指令、技能族、pre/postcondition。
3. 接缝边：相邻节点一条边；类型、entry condition、predecessor residue、repair primitives。
4. 谓词：用视觉（物体/容器/夹爪）+ 本体（EE 位姿、关节、夹爪开度）+ 学习 gate 组合；先用几何/关键词规则，再用小模型校准。
5. 人工审计：5 个任务 × 5 个视频做边界标注；计算 κ；不一致的接缝降级为“仅 type，不强制 gate”。

**输出**：`seam_graph.json`（32 tasks / 94 skills / 62 seams），作为训练、推理、诊断、联邦的共同 schema。

### 4.3 技能调度器：schedule-first，router-second

**为什么不用纯学习 router**：

- 32 个任务的步骤是官方公开的，任务指令可识别；不需要让模型从零发现技能序列。
- 纯学习 router 容易跳步、假完成、在相似观测下选错技能（ManiUnit 的“skill ambiguity”）。
- 评测是单模型多任务，但每个 episode 的指令是已知的；我们可以用确定性计划降低方差。

**做法**：

```text
task = match_instruction(obs.language)          # 5 paraphrases
k = 0
while k < len(sg[task].skills):
    skill = sg[task].skills[k]
    if k > 0 and not gate(obs, sg[task].seams[k-1].entry):
        obs = handoff_expert(obs, sg[task].seams[k-1])
    action_chunk = policy(obs, skill_token(skill), k=top_k_context)
    obs = env.step(action_chunk)
    if undo_detected(obs, skill):
        k = max(0, k-1); continue
    if skill.post(obs):
        k += 1
    else:
        repair(obs, skill)                       # nudge/regrasp/retry
```

学习 router 只作为 fallback：当 gate 无法判断当前技能是否完成时，用一个小分类头在相邻技能之间做选择；不负责全局计划。

### 4.4 Skill-MoLE：单 checkpoint 的技能专家库

**底座**：WLA-1.0-Base，VLM 冻结，action expert 可训。

**专家**：

- 共享专家：所有技能段的通用数据；防止小样本专家过拟合。
- F1–F9 九个技能族专家：每个是一个 LoRA（rank 16–32），挂在 action expert 的 attention + FFN 上；只在自己技能族的数据上训练，但混入 10–20% 共享数据。
- Handoff 专家：第 10 个 LoRA，专门训练接缝窗口/恢复片段；用 `HANDOFF` token 激活。
- 终局放置专家（可选）：F2 的子专家，专门训练 28/32 的终局操作；如果 F2 数据足够，先不单独设，避免专家过多。

**路由**：

- chunk-level top-1：每个 action chunk 只选一个技能专家；技能 token 来自调度器，router 只做“确认/纠错”。
- 公式：\(e = \arg\max_e (\text{router}(h_t) + \lambda \cdot \text{prior}(e|\text{skill}))\)；prior 是 one-hot 技能族，\(\lambda\) 大（如 2.0）时接近 schedule-first。
- load balance：每个 expert 的 token 比例偏离均匀分布时加辅助损失；防止所有 chunk 都选共享专家。
- top-2 消融：只在技能边界附近允许 top-2，其他 top-1。

**单模型合规**：

- 训练期：一个 checkpoint + 多组 LoRA；所有专家共享底座。
- 推理期（首选）：蒸馏成一个稠密 adapter，技能 token 作为条件；只有一个模型。
- 推理期（fallback）：MoLE 在 checkpoint 内；若官方认定多专家不是单模型，改用稠密蒸馏版。

**实现要点**：

- WLA 的 action expert 是 DiT/flow；LoRA 注入 `to_q/to_k/to_v/to_out.0` 与 FFN（`ff.net.0.proj`、`ff.net.2`，以实际模块名为准）。
- 每个 expert 的 LoRA A/B 分开存；训练时只激活当前 expert 的梯度；推理时按 chunk 合并/切换。
- 合并公式（CORAL/Moira 思路）：\(W' = W + \sum_e \alpha_e B_e A_e\)；如果 top-1，直接 \(W + B_e A_e\)，切换成本 O(1) 矩阵加。
- 切换频率：chunk 级（约 0.5–2s），不是 token 级；避免抖动。

### 4.5 Handoff Expert：接缝修复专家

**训练数据**：

1. **自然接缝**：每条接缝切出前序终态 + 后继前 1–2s 的动作；标签为“后继成功/失败”。
2. **异常接缝**：对前序终态做扰动（物体平移/旋转、夹爪姿态偏移、容器位置偏移、遮挡），用后继技能执行；失败的状态作为 handoff 的输入，修复动作由人工/脚本定义。
3. **undo 剧本**：官方 human 备注（T27 叠了又拿、T19 拉上又拉开、T14 拧开又拧回、T17 合上又打开）→ 回滚/重执行。
4. **失败恢复**：抓空、掉落、插入卡住、拉链卡布；用 SRB 的修复原语标注。

**动作空间**：与主策略相同（joint 或 ee）；handoff 只输出短窗口（0.5–2s），然后交回主策略。

**损失**：flow/action loss + 接缝成功分类 + 修复动作的 BC；接缝窗口加权 \(w = 1 + \alpha \cdot 1[\text{within 2s of seam}]\)。

**为什么单独一个专家**：

- 接缝窗口的观测分布与技能内分布不同（物体被前序移动、夹爪姿态不对）；共享专家会被技能内数据淹没。
- SCE 的“执行专家 + 转移专家”双分支证据；Baton 的 transition-aware memory 证据；OSS 的 seam-robust fine-tuning 证据。
- 接缝数据只占全数据的一小部分（62 条接缝 × 1k 条 ≈ 62k 窗口），单独专家更容易欠采样/过采样平衡。

### 4.6 Handoff Gate：entry condition 检查

**输入**：4 路 RGB（下采样）+ EE 位姿 + 关节 + 夹爪开度 + 当前技能/下一技能 ID。

**输出**：`ready / not_ready / undo` + 失败类型（H1–H5）+ 建议修复原语。

**实现**：

- 确定性谓词：夹爪开度阈值、EE 位姿在工作空间、物体在腕部视野、目标在头部视野、容器角度、无人类手。
- 学习头：一个小 MLP/Transformer 在冻结视觉特征上做二/三分类；用接缝数据训练；推理 <5ms。
- 时序：连续 3 帧一致才切换，避免抖动；gate 只在接缝窗口激活，不全程运行。

**阈值**：按技能族校准；放置/插入类更严（避免半途启动），折叠/拉链类更松（需要交互探索）。

### 4.7 Seam Retrieval（SR）

**目的**：给定前序终态，检索“下一技能如何从这种状态启动”的 K 条演示；解决 OSS 的分布偏移。

**键**：

- 对象中心：目标物体/容器的相对位姿（从检测/分割 + EE 位姿估计）。
- 机器人：EE 位姿、夹爪开度、关节（低维）。
- 语言：下一技能指令的嵌入。
- 相位：当前技能 ID + 接缝类型。
- **不用**全局背景/光照作为主键；背景只做弱特征，避免背景轴过拟合。

**库**：挑战集 97.8k 技能段；每段存首帧/前 2s 的键 + 动作片段 + 终态成功标签；用 FAISS/Annoy 检索。

**用法**：

- 训练期：检索到的片段作为 handoff expert 的辅助数据（同接缝类型优先）。
- 推理期：检索到的动作片段作为 **参考**，不直接复制；用目标残差/相对位姿注入策略（与第 7 轮 ICR 一致）。
- 延迟：预编码缓存；每接缝一次检索；K=3–5；<20ms。

**与 ICR 的区别**：ICR 是任务级/语义子任务检索；SR 是**接缝级**检索，键包含前序终态，目标是下一技能的启动。

### 4.8 CSA：Chained-State Augmentation

**核心**：数据里已经有 33k 条全任务演示；每条演示的每个接缝都有一个自然的前序终态。标准训练把整条轨迹当一个任务，接缝窗口的权重很低；CSA 把接缝段显式切出来，训练下一技能从**前序终态**启动。

**步骤**：

1. 用 SG + 变化点检测 + 少量人工标注，切出 94 个技能段。
2. 对每条接缝，取前序终态的观测 + 后继技能的 1–2s 动作，作为一条训练样本。
3. 对前序终态做扰动：
   - 物体平移/旋转（图像空间 + 3D 位姿，若有估计）；
   - 夹爪开度/姿态偏移；
   - 容器位置/角度偏移；
   - 遮挡/背景替换（仅用于视觉鲁棒性）。
4. 用当前策略执行扰动后的后继技能；失败样本进入 handoff expert 的负例/恢复集。
5. 课程：先自然接缝，再小扰动，再大扰动；先终局接缝，再前序接缝。

**可行性**：不需要新仿真器；用离线数据 + 图像/位姿扰动即可。真实机器人上的在线扰动只在调试槽做少量验证。

### 4.9 Placement Seam Toolkit（第 7 轮保留）

终局放置/闭合/插入是最高优先级接缝；保留第 7 轮的：

- **PGL**：槽位/区域 → 2D 锚点 → 6D 位姿的放置目标阶梯。
- **OPT**：K 条演示的“容器系释放位姿”中位数 + 离散度；少样本位姿迁移。
- **SVL**：伺服 → 缓放 → settle → 谓词/PCR/视觉校验 → nudge/regrasp/retry。
- **终局接缝特化**：终局 handoff gate 更严；终局 handoff expert 专门训练“释放/闭合/插入”的修复。

### 4.10 SRB：Seam Recovery Bank

- 官方 human 备注 → undo 剧本：T27 叠了又拿、T19 拉上又拉开、T14 拧开又拧回、T17 合上又打开、T24 可乐/薯片快到了又放回起点。
- 通用恢复原语：retract / open_gripper / re_localize / regrasp / re_stage / re_align / retry / rollback。
- Φ 下降检测：如果当前步骤的进度/谓词从“完成”掉回“未完成”，触发 rollback 到上一个稳定技能。
- 训练：恢复片段作为 handoff expert 的额外数据；推理：gate 输出 `undo` 时调用。

### 4.11 MoLE→Dense Distillation

**为什么**：

- 单模型合规：最终提交一个稠密 checkpoint。
- 延迟：不需要运行时切换 10 个 LoRA。
- 稳定：避免 router 在评测时的分布外抖动。

**学生模型**：

- WLA-1.0-Base + 一个稠密 LoRA（rank 32–64），或 action expert 全量微调（24GB 可能不够，优先 LoRA）。
- 输入：观测 + `skill_token`（技能族 + 步骤索引 + 接缝类型）+ 检索上下文。
- 输出：action chunk。

**蒸馏损失**：

```text
L = L_act(student, demo)
  + λ1 * MSE(student_action, teacher_action)
  + λ2 * KL(student_router, teacher_router)
  + λ3 * L_gate
  + λ4 * L_seam_window
```

**数据**：32 任务全量 + 62 接缝窗口过采样 + 检索上下文 + handoff 修复片段。

**验收**：全任务成功率掉 ≤2pp；接缝通过率掉 ≤3pp；p99 延迟达标；否则保留 MoLE 并做合规复核。

### 4.12 训练配方

| 阶段 | 数据 | 训练 | 产出 | 算力 |
|---|---|---|---|---|
| S0 基线 | 32 任务全量 | WLA LoRA（单卡 24GB） | task-level baseline | 1×24GB |
| S1 技能切段 | 97.8k 技能段 | 变化点 + 人工校准 | SG + 技能段标签 | CPU + 少量标注 |
| S2 技能专家 | 技能段 | 9 个 LoRA，逐个训练 | expert bank | 1×24GB × 9 |
| S3 Handoff | 62k 接缝窗口 + 扰动 | LoRA + 接缝分类 | handoff expert | 1×24GB |
| S4 Gate | 接缝状态 | 小头 + 谓词校准 | gate | CPU/单卡 |
| S5 检索 | 97.8k 段 | 键编码 + 索引 | SR bank | CPU/单卡 |
| S6 CSA | 扰动接缝 | 后继技能微调/难负例 | 接缝鲁棒专家 | 1×24GB |
| S7 联邦 | 官方任务分区 | FedAvg/Co-VLA/MoSAIC | assembled MoLE | 2–4×24GB |
| S8 蒸馏 | 全量 + 接缝 | 稠密 LoRA | final dense | 1×24GB |
| S9 评测 | 调试槽 + 计分跑 | — | go/no-go | 平台 |

**课程**：先易后难（Easy 12 → Medium 12 → Hard 8）；先终局接缝（T27/T19/T10/T26）再前序接缝；先单臂再双手；先刚性再可变形。

### 4.13 推理循环与延迟

```text
reset()
task = match(instruction)
for k, skill in enumerate(sg[task].skills):
    if k > 0:
        seam = sg[task].seams[k-1]
        ready, fail_type = gate(obs, seam)
        if not ready:
            obs = handoff(obs, seam, fail_type)   # 0.5–2s
    ctx = retrieve(obs, skill, k)                 # K=3–5, cached
    for chunk in policy(obs, skill_token(skill), ctx):
        obs = env.step(chunk)
        if undo(obs): rollback(); break
    if not skill.post(obs): repair(obs, skill)
```

**延迟预算**：

- 观测编码 + 策略：目标 <100ms/chunk（取决于 WLA 服务）。
- Gate：<5ms；检索：<20ms；handoff：短窗口，额外 0.5–2s（180s 内可承受）。
- 终局 SVL：每个放置点 1–3s；长任务限次数。
- p99 必须低于平台超时/延迟要求；稠密模型优先。

## 5. 联邦技能工厂（FSF）

### 5.1 为什么联邦：接缝状态是异构的

OSS 的结论是：接缝失败的主导偏移是**被前序技能移动的场景状态**，不是机器人关节。不同实验室的桌面布局、背景、容器位置、人的干扰方式，会生成不同的“前序残留”。**每个实验室都是接缝状态发生器。** 联邦的价值不是“数据量”，而是“接缝状态的多样性 + 数据不出域”。

### 5.2 官方数据上的虚拟联邦（默认路径，合规）

**目的**：在不引入外部数据的前提下，验证“联邦装配”是否优于集中式多任务训练。

**划分**：4 个虚拟客户端，按技能族/难度分：

- C1：放置/堆叠/挂（T20/T21/T25/T27/T01/T08/T24）。
- C2：开合/拉链/锁（T09/T17/T18/T19/T23/T29/T31）。
- C3：插入/双手/装配（T10/T26/T05/T12/T32/T28）。
- C4：折叠/倾倒/取出/整理（T16/T14/T11/T15/T30/T13/T22/T06/T04/T07/T02/T03）。

每个客户端只本地训练自己技能族的 LoRA（共享底座冻结）；server 用 FedAvg / Co-VLA ADMM / RoboFL MoSAIC 装配成 MoLE；router/gate 在 server 的官方链式状态上训练；最后蒸馏成稠密模型。

**对照**：集中式 32 任务 LoRA（E0）vs 虚拟联邦（E7）；看全任务成功率、接缝通过率、通信量、遗忘。

**预期**：如果任务异质性强，联邦装配可能减少负迁移；如果官方数据同分布，联邦可能只 match 集中式。无论结果如何，都是可发表的负/正结果。

### 5.3 真实实验室联邦（条件路径，默认 OFF）

**前提**：书面确认外部自采数据允许用于竞赛；否则只做赛后研究/协议。

**节点**：2–3 个有 G1/Dex1 的实验室，每个负责 1–2 个技能族；本地数据不出实验室。

**交付**：

- LoRA adapter（rank 16–32，~10–50MB）。
- 接缝清单 JSONL：`task_id, seam_id, prev_skill, next_skill, entry_ok, failure_mode, repair, data_hash`；默认不含原始图像。
- 本地评测报告：技能段成功率、接缝通过率、失败类型分布。

**server**：

- 校验 adapter 形状/数据 schema/许可。
- MoSAIC/RoboFL 装配；Co-VLA/FedAvg 对照。
- 在官方链式状态上训练 router/gate（server 持有官方数据）。
- 蒸馏成稠密模型；回发；本地复核。

**轮次**：2–3 轮；每轮 1–2 周；通信 <1GB/client/round；LoRA only。

### 5.4 协议：适配器合同 + 接缝合同

**适配器合同**：

```json

  "skill_family": "F3_open_close_zip",

           "target_modules": ["to_q","to_k","to_v","to_out.0"]},

```

**接缝合同**：同 §3.3；实验室只需填 entry/failure/repair，不需要交原始视频。

> 注：WLA 官方 `trainer.lora` 文档列出的是 attention 模块；FFN LoRA（`ff.net.0.proj`/`ff.net.2`）是自定义扩展，需先确认实际模块名与注入接口。若 FFN 注入成本高，先只做 attention LoRA，MoLE 的专家隔离仍然成立。

**QA**：

- adapter 形状/数值健康（无 NaN、范数合理）。
- 数据 schema/许可/去标识。
- 本地 held-out 接缝测试：低于 baseline 的 adapter 拒绝。
- 服务器聚合后在官方 held-out 任务上评测；掉点 >2pp 的客户端降权/剔除。

### 5.5 聚合算法

| 算法 | 适用 | 风险 |
|---|---|---|
| FedAvg | 同构技能族、简单 | 异构任务可能负迁移 |
| Co-VLA（ADMM） | 异构客户端、需要共识 | 需要更多轮/调参 |
| RoboFL/MoSAIC | 直接把 LoRA 装成 MoE 专家；router 学习 | 需要 server 端 router 数据 |
| 单轮 FedVLA | 只能通信一次 | 精度可能不足 |

**默认**：官方虚拟联邦先用 FedAvg 做 sanity check，再用 Co-VLA/MoSAIC 做主实验；真实实验室用 MoSAIC + 蒸馏。

### 5.6 蒸馏与分发

- Server 用官方 32 任务 + 接缝窗口训练稠密学生；技能 token 条件化。
- 学生回发；客户端本地复核；不满意则保留本地专家，不强行合并。
- 模型卡记录：底座、数据来源、专家列表、蒸馏损失、许可。

| 路由粒度 | chunk / token | 哪个稳？ |
| top-k | 1 / 2 | 接缝处 top-2 是否有益？ |
| Handoff 窗口 | 0.5 / 1 / 2s | 多长够？ |
| Gate 阈值 | 0.5 / 0.7 / 0.9 | 严/松的 trade-off |
| 检索 K | 1 / 3 / 5 / 10 | 延迟 vs 收益 |
| CSA 比例 | 0 / 25 / 50 / 100% | 扰动强度 |
| 联邦 | 集中 / FedAvg / Co-VLA / MoSAIC | 装配收益 |
| 蒸馏 | 无 / 稠密 LoRA / 全量 | 掉点/延迟 |
| 终局专家 | 无 / 单独 | 终局是否需要专属专家 |

### 6.3 诊断矩阵

| 现象 | 可能原因 | 检查 | 对策 |
|---|---|---|---|
| 技能单独成功、链式失败 | OSS / 接缝 | 接缝通过率 | handoff + CSA |
| 终局失败 | 放置/闭合/插入 | 终局误差/谓词 | Placement Toolkit |
| 技能选错 | router/歧义 | 路由混淆矩阵 | schedule-first |
| 接缝抖动 | gate 阈值 | 连续帧一致性 | 时序平滑 |
| 人类干扰后卡住 | undo 未检测 | Φ 下降 | SRB rollback |
| 长任务超时 | 重试过多 | 每步耗时 | 限重试/加速 |
| 联邦掉点 | 客户端异构 | 客户端权重 | personalization/剔除 |

### 6.4 调试槽计划

平台有“不计分单任务调试”模式 [S7]；用它做接缝级 go/no-go，不做精细调参。

| 槽 | 任务 | 接缝数 | 看什么 | 决策 |
|---|---|---:|---|---|
| D1 | T27 StackBowls | 2 | 终局接缝 + undo | handoff/gate 是否有效 |
| D2 | T10 PlugCharger | 2 | 双手/插入接缝 | 插入 handoff 是否有效 |
| D3 | T19 ZipUp | 1 | 拉链接缝 | 可变形接缝是否有效 |
| D4 | T16 FoldTowel | 4 | 4 条接缝 | 长链接缝是否累积 |
| D5 | T17 OrganizeStationery | 4 | 4 条接缝 | 容器/闭合接缝 |

**注意**：调试槽只返回任务成功/步骤分；接缝级通过率来自我们自己的日志（策略内部的技能切换、gate 输出、谓词结果）。如果平台提供逐步分，优先用平台数据。

### 6.5 统计与决策规则

- 训练 3 seeds；检索/蒸馏 3 seeds；报告均值 ± 95% CI。
- 主比较用配对 bootstrap（同任务、同轴）。
- +5pp 才认为有意义；+2pp 不下结论。
- 若 E3/E4 的接缝通过率提升 <5pp，停止 handoff 路线，回退到 E0 + Placement Toolkit。
- 若 E8 蒸馏掉 >2pp，保留 MoLE；若合规不允许，改用技能 token + 单 LoRA。
- 若 E7 联邦掉 >2pp，联邦只保留为协议/赛后研究。

## 7. 创新点清单

> 状态：押注 / 保留 / 条件 / 降级 / 砍。每项给动机、差异、可行性、资源、步骤、风险。

### I1 SG：Seam Graph（升级 SSG）｜押注

- **动机**：32 任务 = 94 技能 + 62 接缝；终局 32/32 最高权重；接缝是独立失败源。
- **差异**：第 7 轮 SSG 只有步骤节点；SG 增加接缝边、entry condition、predecessor residue、repair primitives。
- **可行性**：`score_steps` 全公开；5 条复述；数据可切段；人工审计 5 任务。
- **资源**：1 人 × 1 周；CPU + 标注。
- **步骤**：解析 32 info.json → 建 94 节点/62 边 → 谓词模板 → 5 任务人工校准 → JSON schema。
- **风险**：接缝标签噪声；用 κ≥0.8 和“只对高置信接缝强制 gate”控制。
- **产出**：`seam_graph.json` + USSB 的核心。

### I2 Skill-MoLE：单 checkpoint 技能专家库｜押注

- **动机**：32 任务共享容量会互相拉扯；技能段 97.8k 足够训专家；WLA 支持 LoRA/24GB。
- **差异**：不是每任务 LoRA；是 9 个技能族专家 + 共享专家 + handoff 专家；chunk-level top-1；最终蒸馏。
- **可行性**：单卡逐个训；专家小（rank 16–32）；WLA action expert 可注入。
- **资源**：1–2 人 × 2 周；1×24GB × 9 次训练。
- **步骤**：切段 → 训共享 → 训 9 专家 → 装配 → 路由 → 蒸馏。
- **风险**：路由坍缩、专家数据不均、蒸馏掉点；用 schedule-first、load balance、≤2pp 验收。
- **产出**：expert bank + 稠密学生。

### I3 Handoff Expert：接缝修复专家｜押注（本轮主创新）

- **动机**：OSS/Baton/Semantic Handoff/SCE 都指向“转移”是独立能力；接缝窗口数据分布不同。
- **差异**：不是 LLM agent（Baton），不是纯恢复策略（OSS），而是一个在同一 checkpoint 内的 LoRA 专家；用 `HANDOFF` token 激活；训练数据是 62 条接缝的自然/扰动/undo 片段。
- **可行性**：62k 自然接缝窗口；修复原语可脚本化；短窗口。
- **资源**：1 人 × 2 周；1×24GB。
- **步骤**：切接缝 → 标成功/失败 → 扰动 → 训 handoff → 接 gate → 调窗口。
- **风险**：修复动作覆盖不全；用 SRB 原语 + 人工少量标注；先终局接缝。
- **产出**：handoff LoRA + 接缝恢复数据集。

### I4 Handoff Gate：entry condition 检查｜押注

- **动机**：后继技能启动前必须满足 entry condition；纯策略不会显式检查。
- **差异**：确定性谓词 + 小学习头 + 时序平滑；不是 VLM critic；<5ms。
- **可行性**：EE/关节/夹爪/视觉都可算；接缝数据可训。
- **资源**：0.5 人 × 1 周；CPU/单卡。
- **步骤**：谓词库 → 阈值校准 → 学习头 → 连续帧一致 → 接缝类型分桶。
- **风险**：误判导致不必要的 handoff；用“只在高置信失败时触发”保守策略。
- **产出**：gate head + 谓词库。

### I5 CSA：Chained-State Augmentation｜押注

- **动机**：数据里已有 33k 条演示的接缝终态；标准训练没利用。
- **差异**：不是仿真 reset；是离线切段 + 前序终态训练 + 图像/位姿扰动 + 难负例。
- **可行性**：不需要新仿真器；用现有数据。
- **资源**：1 人 × 1.5 周；CPU + 单卡。
- **步骤**：切段 → 前序终态 → 扰动 → 训后继 → 失败挖掘 → 课程。
- **风险**：扰动不真实；用真实演示的自然变体为主，扰动为辅。
- **产出**：接缝鲁棒训练集。

### I6 SR：Seam Retrieval（升级 ICR）｜押注

- **动机**：OSS 的分布偏移可以用“相似前序终态”的演示来条件化；任务级检索不够。
- **差异**：键包含前序终态 + 下一技能 entry + 关系位姿；不是全局外观。
- **可行性**：97.8k 技能段；FAISS；缓存。
- **资源**：0.5 人 × 1 周；CPU/单卡。
- **步骤**：键编码 → 索引 → 接缝类型过滤 → K=3–5 → 注入策略。
- **风险**：透明/布料检索不稳；分桶回退到“接缝类型 + 动作先验”。
- **产出**：SR bank + 检索接口。

### I7 Placement Seam Toolkit：终局接缝特化（保留）｜押注

- **动机**：终局 32/32 最高权重，28/32 是放置/闭合/插入/倾倒/取出。
- **差异**：第 7 轮 PGL/OPT/SVL 保留，但放进 SG 的终局接缝；gate 更严。
- **可行性**：第 7 轮已设计；数据/接口支持。
- **资源**：1 人 × 2 周。
- **步骤**：终局接缝标定 → PGL 锚点 → OPT 位姿 → SVL 闭环 → 重试限次。
- **风险**：终局接缝前面的误差导致到不了终局；用通用接缝先兜底。
- **产出**：终局接缝模块。

### I8 SRB：Seam Recovery Bank（升级 NRB）｜保留

- **动机**：官方 human 备注大量“先完成再撤销”。
- **差异**：从“恢复库”升级为“接缝 undo 剧本 + Φ 下降检测 + rollback”。
- **可行性**：备注已抓全；恢复原语可脚本化。
- **资源**：0.5 人 × 1 周。
- **步骤**：解析备注 → 剧本 → 原语 → 训练/触发。
- **风险**：备注编号含义不明；按文本内容而非编号使用。
- **产出**：SRB 数据集 + 触发器。

### I9 MoLE→Dense Distillation｜押注（合规关键）

- **动机**：单模型规则 + 延迟；最终提交必须是稠密 checkpoint。
- **差异**：技能 token 条件化 + 接缝窗口加权 + router KL；不是简单平均。
- **可行性**：WLA + 单 LoRA；24GB；3 seeds。
- **资源**：1 人 × 1.5 周；1×24GB。
- **步骤**：学生初始化 → 教师数据 → 蒸馏 → 验收（≤2pp）→ 模型卡。
- **风险**：掉点；回退 MoLE 或技能 token 单 LoRA。
- **产出**：最终稠密模型。

### I10 FSF：Federated Skill Factory｜条件（本轮主创新之二）

- **动机**：接缝状态异构；实验室是接缝发生器；数据不出域。
- **差异**：不是普通联邦 VLA；是“技能适配器 + 接缝合同”的联邦装配；先官方虚拟联邦，再真实实验室。
- **可行性**：官方 32 任务可虚拟分区；LoRA 单卡；RoboFL/Co-VLA 有代码/证据。
- **资源**：1 人 × 2 周；2–4×24GB。
- **步骤**：分区 → 本地 LoRA → 装配 → router/gate → 蒸馏 → 对照。
- **风险**：异构导致掉点；用 personalization/剔除；真实实验室规则未明，默认 OFF。
- **产出**：FSF 协议 + 虚拟联邦结果 + 赛后真实联邦。

### I11 SDP：Seam Diagnostic Protocol（升级 DebugLoop）｜工程策略

- **动机**：任务级指标掩盖接缝失败；调试槽稀缺。
- **差异**：内部接缝日志 + gate 输出 + 谓词结果 + 失败类型；调试槽只做 go/no-go。
- **可行性**：策略侧可日志；平台只给任务级结果。
- **资源**：0.5 人 × 1 周。
- **步骤**：日志 schema → 接缝事件 → 汇总 → 决策规则。
- **风险**：日志与平台结果不一致；以平台成功率为准。
- **产出**：SDP dashboard/报告。

### I12 USSB：UniBot Skill & Seam Benchmark｜赛后公共品

- **动机**：32 任务的 skill/seam 结构没有公开 benchmark；产学研需要共同 schema。
- **差异**：94 技能 + 62 接缝 + entry condition + 失败类型 + 修复原语；不是又一个任务集。
- **可行性**：info.json 公开；人工审计 5 任务；数据许可待确认。
- **资源**：1 人 × 1 周（赛后）。
- **步骤**：schema → 标注 → 评测脚本 → 开源。
- **风险**：竞赛期间不宜开源核心权重；只开源 schema/标注。
- **产出**：USSB v0.1。

### I13 GPR-VLA / WLA 底座（保留）

- 第 7 轮保留；本轮只改“技能 token + MoLE + 蒸馏”的接口。
- 风险：WLA 的 Dex1-only 动作空间与 UniBot 接口对齐；第 7 轮已确认。

### I14 TLE/ACP/GF 数据引擎（保留，修剪）

- TLE：技能段/接缝标签；ACP：接缝反事实；GF：容器/目标位姿。
- 修剪：不再做全 32 任务高保真孪生；只做接缝状态离线扰动。

### I15 FLEET 工程检查单（降级｜第 6 轮遗产）

- N 端口并发、状态隔离、延迟弹性、健康检查、日志；作为部署检查单，不作为研究主轴。

### 已砍清单（跨轮）

- 每任务 LoRA / 多模型混合（违反单模型）。
- 全 32 任务高保真孪生（成本高、收益低）。
- 自由仿真数据 / 仿真 RL（sim-to-real 风险）。
- 运行时仿真/MPC（延迟/规则风险）。
- 布料/拉链/透明全物理（先做接缝，不做全物理）。
- 真事件相机 / 真 IMU（API 不提供）。
- 步骤分 farming（成功率优先）。
- 独立 VLM critic（延迟/单模型风险）。
- 全 world model 进主路径（算力/延迟）。

## 8. 风险、合规与停止条件

### 8.1 规则风险

| 风险 | 现状 | 对策 |
|---|---|---|
| 单模型解释 | 手册说单模型；MoLE 是否算单模型未确认 | 最终稠密蒸馏；模型卡；邮件确认 |
| 外部数据 | 手册 2.2 后截断；辅助集许可不等于竞赛许可 | 默认 OFF；官方虚拟联邦；书面确认 |
| 调试槽 | 次数/费用/排期未确认 | 每版本 1 槽；只做 go/no-go |
| 截止日期 | 未确认 | 8 周计划；每周检查官网 |
| 步骤分公式 | 假设每步二值 | 以官方为准；不刷分 |
| 语言复述 | 5 条已核实；评测是否采样未确认 | 训练覆盖 5 条；中文映射 |
| 180s | 已核实单次上限 | 限重试；p99 延迟预算 |
| 动作空间 | joint/ee 二选一；Dex1-only | 第 7 轮已对齐；不混用 |

### 8.2 技术风险

| 风险 | 触发 | 缓解 | 停止条件 |
|---|---|---|---|
| 接缝标签噪声 | κ<0.8 | 人工校准、只对高置信接缝 gate | 降到任务级 |
| Handoff 数据不足 | 修复片段 <1k | SRB 原语、扰动、终局优先 | 只做终局接缝 |
| 路由坍缩 | 某专家 >70% chunks | schedule-first、load balance | 改技能 token |
| 蒸馏掉点 | >2pp | 加大学生 rank、接缝过采样 | 保留 MoLE/合规复核 |
| 联邦掉点 | >2pp | personalization、剔除 | 联邦只做研究 |
| 延迟 | p99 超预算 | 稠密模型、缓存检索、限 handoff | 降 K/关 handoff |
| 透明/布料 | 检索/谓词失效 | 分桶回退动作先验 | 不做位姿迁移 |
| 人类干扰 | undo 检测失败 | Φ 下降 + 视觉 | 保守回滚 |
| 长任务超时 | 重试过多 | 限重试、加速 | 降级到任务级 |

### 8.3 组织风险

- 实验室协调：先签数据/许可/署名协议；先做 2 个节点试点。
- 算力：单卡 24GB 可逐个专家训练；联邦 server 需要 2–4 卡。
- 时间：8 周；先终局接缝 + 官方虚拟联邦，真实联邦赛后。
- IP：竞赛期间不开源核心权重；赛后开源协议/benchmark。

### 8.4 停止条件（go/no-go）

1. 接缝标签 κ<0.8 → 停止技能专家，回退任务级 + 终局接缝。
2. E3/E4 接缝通过率提升 <5pp → 停止 handoff，回退 E0 + Placement Toolkit。
3. E8 蒸馏掉 >2pp → 保留 MoLE/技能 token 单 LoRA；不做稠密。
4. E7 联邦掉 >2pp → 联邦只做协议/赛后；竞赛用集中式。
5. 调试槽连续 2 次低于 baseline → 暂停提交，先修数据/标签。
