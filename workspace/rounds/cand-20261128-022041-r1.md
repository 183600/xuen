### 第 5 轮灵感驱动研究记录

**灵感词**：伦理审查、演示方案

**继承关系**：第 4 轮 CADVS-v4（IP-489~492）在 v3 五锚点上追加价值锚 VACK 与平衡锚 BCK，形成七硬门 kc_evidence_forged_v4 = kc_coverage ∧ kc_physics ∧ kc_human ∧ kc_ee ∧ kc_mem ∧ kc_val ∧ kc_bal，软评分 ECS_v4 = ECS_v3 · η_val · η_bal，执行集 Exec_CADVS-v4 ⊆ Exec_CADVS-v3 ⊆ Exec_CADVS-v2 ⊆ Exec_CADVS-v1 ⊆ Exec_v29。v4 的最大遗留问题是「所有证据都被塞进同一个控制环时标」，实时性风险靠异步化与近似勉强压住。本轮不推翻 v4，而是把「伦理审查」与「演示方案」提升为一等证据，并引入时标分层，形成 CADVS-v5（IP-493~496）。关键变化：**控制环内执行集不变**（Exec_cycle-v5 = Exec_CADVS-v4），但**部署/发布集收缩**为 Exec_Deploy-v5 ⊆ Exec_CADVS-v4。

**直觉与动机**：

1. **伦理审查：从「价值对齐」到「制度可问责」**。v4 的 VACK 是一个内部奖励模型，回答「这条轨迹是否符合人类价值」，但它回答不了「谁授权了这次部署、授权范围多大、何时过期、出问题谁负责」。真实机器人部署需要的不是更高的 α_val，而是可审计的程序合法性。伦理审查本质上是一个**带状态的程序性证书**：有提交、审查、附条件批准、暂停、过期、撤回，有管辖范围、知情同意来源、数据治理、双重用途评估、监督链、异议与申诉。把伦理审查硬编码为一个标量会丢掉最关键的东西——**范围、时效、责任与异议**。因此引入伦理审查证书 ERC 与硬门 kc_eth，并保留「机构否决」（stop-order）作为与 HIC veto 并列的最高优先级旁路，只是时标更慢。

2. **演示方案：从「实验设计」到「可证伪、可复现的演示契约」**。v4 有实验设计，但实验设计与「向审查者证明」之间缺少绑定：声明、场景、仪器、阈值、见证、复现哈希是分离的。演示方案不是 PPT 和剪辑视频，而是一份**声明-证据契约**：每条 claim 必须绑定场景、仪器、指标、阈值、样本量与证伪条件；演示必须可重放（replay hash）、可被独立见证、可在 kill switch 下安全终止。引入演示契约 DMC 与硬门 kc_demo。这把「论文创新点」落成「可被第三方复核的演示包」，也让「演示」本身成为可检验的证据，而不是叙事。

3. **时标分层：用「证据的时间结构」解决 v4 的实时性硬伤**。v4 把 VACK（10–50 ms）与 BCK（1–5 ms）都往 1 kHz 控制环里塞，靠异步化与近似勉强达标。但伦理审查（周级）与演示方案（里程碑级）根本不该进入控制环。真正的一般性洞见是：**不同证据有不同的有效期与刷新率，安全不是一个时标上的合取，而是多个时标上的分层合取**。定义 L0 控制（1 kHz）、L1 准入（秒级）、L2 演示（每次发布）、L3 伦理（周级）。每层有自己的硬门、有效期 H、漂移界 δ 与失效触发器。控制环只跑 L0/L1，因此 v5 不增加任何控制环延迟；L2/L3 只收缩「部署集」。

**关键洞见**：v4 回答「需要哪些证据」；v5 回答「这些证据由谁授权、在多长时间内有效、如何向外部证明」。七锚点仍在 L0/L1；伦理与演示是 L2/L3 治理锚。**执行集（execution）与部署集（deployment）分离**：Exec_cycle-v5 = Exec_CADVS-v4（实时性不变），Exec_Deploy-v5 = Exec_CADVS-v4 ∩ {kc_eth} ∩ {kc_demo}（发布更严）。这把「安全」从「每周期都证明一切」改写为「每个时标证明它该证明的，并用新鲜度把各层缝起来」。

**形式化目标（增量）**：
1. 定义伦理审查证书 ERC = (rid, scope, jurisdiction, board, consent_prov, data_gov, dual_use, oversight, conditions, dissents, issued_at, expires_at, re_review_trigger, sig_set) 与审查状态机；kc_eth = state ∈ Deployable ∧ dep_scope ⊆ scope ∧ fresh ∧ conditions_satisfied ∧ ¬stop_order。
2. 定义演示契约 DMC = (claims[], scenarios[], instrumentation[], bounds, kill_switch, witness, replay_hash, rehearsal, divergence)；kc_demo = claim_coverage = 1 ∧ rehearsal_passed ∧ divergence ≤ ε_demo ∧ kill_switch_verified ∧ witness_signed ∧ replay_ok ∧ ¬unresolved_redteam。
3. 定义时标分层 L = {L0, L1, L2, L3}、有效期 H(c)、漂移界 δ(c)、新鲜度 fresh(c,t)、漂移触发失效。
4. 定义时序证书代数：带 horizon 的 □_{[0,H]}、分层 meet ⊓_L、过期吸收律（stale 证书与任何证书 meet 得 ⊥）。
5. 定理 5（分层可靠性）：若各层硬门在其刷新周期内成立且证书新鲜、漂移有界，则部署集 R(t) 满足各层安全性质的合取，且 L0 实时性与 L2/L3 解耦。
6. 定理 6（时序收缩）：R_v5(t) ⊆ R_v4(t)，且若 kc_eth/kc_demo 非恒真则严格；Exec_cycle-v5 = Exec_CADVS-v4。
7. 给出可执行的演示方案：claim 表、场景矩阵、仪器、阈值、角色、时间线、kill switch、复现与见证、伦理材料清单、dry-run 结果。

**本轮最大风险**：**伦理审查与演示方案都是慢时标、可被「盖章」形式化通过的治理证据，存在 rubber-stamping 与 stale-certificate 风险**——纸面合规、证书未过期，但运行分布或人类价值已漂移，系统仍在「合法」地做错事。

## 2. 关键算法骨架

### IP-493 ERCK：伦理审查证书（L3，周级，完全异步）

```python
@dataclass
class EthicsReviewCertificateKernel:
    """ERCK：伦理审查是带状态的程序性证书，不是标量分数；kc_eth 硬门"""
    deployable_states: frozenset = frozenset({"APPROVED", "CONDITIONAL"})
    sig_quorum: int = 3                 # 审查委员签名法定人数
    max_horizon_days: int = 180         # 证书最长有效期，强制复审

    def kc_eth(self, erc: ERC, dep_scope: Scope, t_now: float,
               drift: float) -> tuple[bool, str]:
        """fail-closed：任一条件不满足即拒；HIC veto 优先级仍更高"""
        if erc.state not in self.deployable_states:
            return False, "ETH_NOT_APPROVED"
        if erc.state == "CONDITIONAL" and not self._conditions_satisfied(erc):
            return False, "ETH_CONDITIONS_UNMET"
        if not self._scope_subset(dep_scope, erc.scope):
            return False, "ETH_OUT_OF_SCOPE"
        if erc.stop_order:
            return False, "ETH_STOP_ORDER"
        if not self._sig_quorum_valid(erc):
            return False, "ETH_SIG_INVALID"
        if not fresh(erc, t_now, drift):          # 见 IP-495
            return False, "ETH_STALE"
        return True, "ETH_OK"

    def institutional_veto(self, erc: ERC) -> bool:
        """机构否决：与 HIC veto 并列的最高优先级旁路，但发生在治理时标"""
        return bool(erc.stop_order)

    def _conditions_satisfied(self, erc: ERC) -> bool: ...
    def _scope_subset(self, dep: Scope, approved: Scope) -> bool: ...
    def _sig_quorum_valid(self, erc: ERC) -> bool: ...
```

**审查状态机**：

```
DRAFT ──submit──▶ SUBMITTED ──assign──▶ IN_REVIEW
   IN_REVIEW ──approve──▶ APPROVED ──expire──▶ EXPIRED
   IN_REVIEW ──conditions──▶ CONDITIONAL ──satisfy──▶ APPROVED
   APPROVED/CONDITIONAL ──dissent(STOP)──▶ SUSPENDED
   SUSPENDED ──resolve──▶ IN_REVIEW
   any ──withdraw──▶ WITHDRAWN
```

**与 VACK 的关系**：VAC 回答「轨迹是否符合价值」，ERC 回答「这次部署是否被制度授权」。VAC 是 ERC 的技术附件之一；ERC 还包含范围、同意、数据治理、双重用途、监督链、责任人与申诉通道。**高 α_val 不能替代伦理批准，伦理批准也不能替代控制环的实时安全门。**

### IP-494 DMCK：演示契约（L2，每次发布，异步）

```python
@dataclass
class DemonstrationContractKernel:
    """DMCK：演示方案 = 可证伪、可复现、可见证的声明-证据契约；kc_demo 硬门"""
    epsilon_demo: float = 0.05          # 复演允许偏差
    required_witnesses: int = 1         # 独立见证人数量

    def kc_demo(self, dmc: DMC, t_now: float) -> tuple[bool, str]:
        if self._coverage(dmc) < 1.0:
            return False, "DEMO_CLAIM_UNCOVERED"
        if not self._rehearsal_passed(dmc):
            return False, "DEMO_REHEARSAL_FAILED"
        if dmc.divergence > self.epsilon_demo:
            return False, "DEMO_DIVERGENCE"
        if not dmc.kill_switch.verified:
            return False, "DEMO_KILL_SWITCH_UNVERIFIED"
        if len(dmc.witness) < self.required_witnesses or not self._witness_signed(dmc):
            return False, "DEMO_WITNESS_MISSING"
        if not self._replay_ok(dmc):       # replay_hash 与 manifest 一致
            return False, "DEMO_REPLAY_MISMATCH"
        if self._unresolved_redteam(dmc, severity_min="high"):
            return False, "DEMO_REDTEAM_OPEN"
        return True, "DEMO_OK"

    def _coverage(self, dmc: DMC) -> float:
        return sum(1 for c in dmc.claims
                   if c.scenario is not None and c.instrumentation) / max(len(dmc.claims), 1)

    def _replay_ok(self, dmc: DMC) -> bool:
        manifest = canonical_manifest(dmc)          # 容器 digest + seed + config + 数据清单
        return sha256(manifest) == dmc.replay_hash

    def _rehearsal_passed(self, dmc: DMC) -> bool: ...
    def _witness_signed(self, dmc: DMC) -> bool: ...
    def _unresolved_redteam(self, dmc: DMC, severity_min: str) -> bool: ...
```

**claim 的最小结构**（缺任一字段即视为未覆盖）：

```python
@dataclass
class Claim:
```

### IP-495 TCS：时标分层与证书代数（离线理论 + 在线新鲜度检查）

```python
@dataclass(frozen=True)
class Stratum:
    name: str          # L0/L1/L2/L3
    cadence_s: float   # 刷新周期
    max_latency: float # 单次评估预算
    gates: tuple       # 该层硬门

L0 = Stratum("L0", 1e-3, 1e-3, ("kc_coverage", "kc_physics", "kc_human",
                                "kc_ee", "kc_mem", "kc_val", "kc_bal"))
L1 = Stratum("L1", 1.0, 2.0, ("kc_val", "kc_physics"))
L2 = Stratum("L2", 7 * 86400, 3600.0, ("kc_demo",))
L3 = Stratum("L3", 30 * 86400, 86400.0, ("kc_eth",))

def fresh(c, t_now: float, drift: float) -> bool:
    return (t_now - c.t_issued < c.horizon) and (drift <= c.delta) and not c.invalidated

def stratified_meet(c, d, t_now: float, drift: float):
    """过期吸收律：任一证书不新鲜，结果为 ⊥（fail-closed）"""
    if not (fresh(c, t_now, drift) and fresh(d, t_now, drift)):
        return BOT
    return Meet(c, d, horizon=min(c.horizon, d.horizon),
                delta=min(c.delta, d.delta))

def invalidate_on_drift(c, D_drift: float) -> bool:
    """漂移触发失效：D_drift 超界即令证书失效，强制复审/复演"""
    return D_drift > c.delta
```

```python
# 定理 5：分层可靠性
def theorem_stratified_soundness() -> str:
    """
    设各层 ℓ ∈ {L0,L1,L2,L3} 的硬门 G_ℓ 在签发时对性质 P_ℓ 可靠（裕度 m_ℓ），
    且在 [t_issued, t] 内证书新鲜：t−t_issued < H_ℓ 且 D_drift ≤ δ_ℓ。
    则 t 时刻任何部署 x ∈ R(t) 满足 ∧_ℓ P_ℓ，且裕度 ≥ min_ℓ m_ℓ。
    证明：签发时逐层可靠性；新鲜度 + 漂移界保证性质在有效期内不越出裕度；
    合取为证书格 meet；L0 每周期门与 L2/L3 发布门解耦，故慢层不进入控制环。
    """
    return "Proven (modulo drift observability)"

# 定理 6：时序收缩与实时性解耦
def theorem_temporal_contraction() -> str:
    """
    ∀t: R_v5(t) ⊆ R_v4(t)。若 kc_eth 或 kc_demo 非恒真，则严格 ⊂。
    Exec_cycle-v5 = Exec_CADVS-v4，故控制环延迟分布逐点不变；
    新增计算只发生在发布时标，不进入 1 kHz 预算。
    证明：发布门是 v4 证据铸造的合取扩展；每周期门未改动；
    非恒真性给出至少一条 v4 可部署而 v5 拒绝的配置。
    """
    return "Proven"
```

### IP-496 RGA-v5：发布门（L2/L3 外层包裹，不改 L0）

```python
@dataclass
class ReleaseGateAssemblerV5:
    """RGA-v5：在 EFA-v4 之外叠加伦理与演示两道发布门；控制环零改动"""
    efa: EvidenceForgingAssemblerV4
    erck: EthicsReviewCertificateKernel
    dmck: DemonstrationContractKernel
    tcs: TemporalCertificateStratification

    def release_gate(self, rule_id, dep_scope, erc: ERC, dmc: DMC,
                     t_now: float, D_drift: float) -> tuple[bool, str]:
        # L0/L1：继承 v4 七硬门（每周期/准入时已分别检查）
        ok_v4, why_v4 = self.efa.hard_gate(...)
        if not ok_v4:
            return False, f"L0L1:{why_v4}"
        # L2：演示契约
        ok_demo, why_demo = self.dmck.kc_demo(dmc, t_now)
        if not ok_demo:
            return False, f"L2:{why_demo}"
        # L3：伦理审查
        ok_eth, why_eth = self.erck.kc_eth(erc, dep_scope, t_now, D_drift)
        if not ok_eth:
            return False, f"L3:{why_eth}"
        return True, "RELEASE_OK"
```

```
        │  预注册、复演、红队、独立见证
        ▼
L1 规则准入（秒级，异步）
    MSRG/S2RC + VACK.evaluate（α_val）+ EFA-v4.hard_gate（含 LTEM/FFA）
        │  规则签发/降权/回退
        ▼
L0 控制环（1 kHz，硬实时，v4 原样不变）
    EEK→EEC→kc_ee ； BCK→BCC→kc_bal ； 七硬门 fail-closed
        │  每周期只跑 L0，延迟预算不增加
        ▼
    执行 / 安全停止
```

| 层 | 时标 | 评估预算 | 硬门 | 失效动作 |
|---|---|---|---|---|
| L0 控制 | 1 ms | < 1 ms/周期 | kc_coverage/kc_physics/kc_human/kc_ee/kc_mem/kc_val/kc_bal | 立即安全停止/回退 |
| L1 准入 | ~1 s | < 2 s/规则 | kc_physics/kc_val/kc_mem | 规则降权/拒绝签发 |
| L2 演示 | 每次发布 | 小时~天 | kc_demo | 阻止发布/要求复演 |
| L3 伦理 | 周~月 | 天~周 | kc_eth | 阻止部署/暂停/撤回 |

**关键性质**：L2/L3 的评估**永远不进入 L0 控制环**；RGA-v5 只在发布时读取缓存的 ERC/DMC，因此 v4 的实时性结论逐点保留。L0 的七硬门仍是每周期 fail-closed，慢层失效不会「放宽」控制环，只会收缩部署集。

## 4. 正确性论证（增量更新）

### 引理 43（伦理审查状态可靠性）

**陈述**：设审查委员会对 ERC 的每条条件以概率 ≥ 1−δ_r 正确核验，签名法定人数正确性以概率 ≥ 1−δ_sig 成立，且运行时条件被重新检查。则当 kc_eth 通过时，部署在 scope 内满足已批准风险包络，概率 ≥ 1 − Σ_r δ_r − δ_sig。

**证明**：条件核验与签名校验独立失败；kc_eth 对 state/scope/conditions/stop_order/fresh 逐项 fail-closed，任一失败即拒；运行时条件违反直接触发拒绝而非继续。∎

**诚实边界**：这条引理只保证「程序按规则执行」，不保证「审查本身是明智的」。伦理审查的社会过程可能被 rubber-stamping，见 R53。

### 引理 44（演示声明覆盖与复现可靠性）

**陈述**：若 DMC 的每条部署关键 claim 都绑定了可执行场景、仪器与预注册阈值，且复演偏差 ≤ ε_demo，则对落在演示场景分布内的部署轨迹，claim 指标以概率 ≥ 1−ε_demo 满足阈值；replay_hash 一致保证第三方可复现。

**证明**：覆盖性保证 claim 不被空口声明；预注册防止事后挑选阈值；复演偏差界给出分布内泛化；哈希链保证 manifest 未被篡改。∎

**诚实边界**：演示只能覆盖「场景分布内」，不能证明开放世界的分布外安全；这正是 R55/R54 的来源。

### 定理 5（分层可靠性）

**陈述**：在 (C1) 各层硬门对其性质可靠（裕度 m_ℓ）、(C2) 证书在有效期内新鲜（t−t_issued < H_ℓ 且 D_drift ≤ δ_ℓ）、(C3) 漂移可观测且界有效 下，t 时刻任何部署 x ∈ R(t) 满足 ∧_{ℓ} P_ℓ，裕度 ≥ min_ℓ m_ℓ；且 L0 的每周期安全性与 L2/L3 的评估频率无关。

**证明**：逐层由 (C1) 在签发时成立；由 (C2) 与漂移界，性质在 [t_issued,t] 内不越出裕度；合取由证书格 meet 给出，过期吸收律保证任一 stale 证书使结果为 ⊥；L0 门集合未引用 L2/L3 运行时状态，故慢层不改变控制环。∎

### 定理 6（时序收缩与实时性解耦）

**陈述**：∀t，R_v5(t) ⊆ R_v4(t)；若 kc_eth 或 kc_demo 非恒真则严格。Exec_cycle-v5 = Exec_CADVS-v4，控制环延迟分布逐点不变。

**证明**：RGA-v5 在 v4 证据铸造之上追加两道合取门；合取只缩不涨；非恒真给出至少一条 v4 可部署而 v5 拒绝的配置；L0 代码路径未改动，故延迟分布不变。∎

### 定理 v5（分层治理的完备性声明）

**陈述**：在 (B1)~(B6) 继承 v4，且 (B7) 漂移可观测、(B8) 审查程序忠实执行、(B9) 演示场景覆盖部署分布 下，v5 的部署集满足：
(i) R_v5(t) ⊆ R_v4(t)（严格，若两新门非恒真）；
(ii) L0 控制环实时性等于 v4（无新增延迟）；
(iii) 伦理合法性由引理 43 界；
(iv) 演示可复现性由引理 44 界；
(v) 分层可靠性由定理 5；
(vi) 过期/漂移触发失效，治理缺口有界。

**证明**：(i)(ii) 定理 6；(iii) 引理 43；(iv) 引理 44；(v) 定理 5；(vi) 由 fresh 定义与 invalidate_on_drift 的单调性。∎

**诚实声明**：(B7) 漂移可观测是最脆弱假设——开放世界中漂移可能缓慢、隐蔽或对抗性；一旦 D_drift 估计失真，stale 证书会被误判为 fresh。(B8) 把伦理审查形式化为谓词，本身是对社会过程的降维，可能诱发「合规表演」。(B9) 演示场景永远无法覆盖开放世界。缓解：漂移监控多信号冗余、随机审计、异议通道、证书短有效期、预注册与红队、独立见证；但这些只能降低风险，不能消除。

## 5. 演示方案（本轮核心产物）

### 5.1 演示目标与可证伪声明

演示的总目标：向独立审查者证明 **「v5 的慢时标治理层不损害 v4 的实时安全，且能有效阻断越界/未证实部署」**。每条 claim 预注册，演示后不得修改阈值。

| ID | 可证伪声明 | 指标 | 场景 | 通过阈值 | 证伪条件 |
|---|---|---|---|---|---|
| C1 | 分层后 1 kHz 控制环仍满足实时预算 | 延迟 P99 / 丢帧率 | S5 | P99 ≤ 1.0 ms；丢帧 ≤ 0.05% | P99 > 1.2 ms 或丢帧 > 0.1% |
| C2 | 越界部署被 kc_eth 100% 拒绝 | 越界通过率 | S2 | 0 / N | 任一越界配置被放行 |
| C3 | 缺失/伪造仪器的 claim 被 kc_demo 100% 拒绝 | 漏检率 | S3 | 0 / N | 任一未覆盖 claim 被接受 |
| C4 | 漂移超界后证书在 T_invalid 内失效 | 失效延迟 | S4 | ≤ 5 s | 超时后证书仍 active |
| C5 | v5 安全违例率不高于 v4 | 违例率 | S1/S6 | ≤ v4 基线 | 显著高于 v4（单侧检验 p<0.05） |
| C6 | 演示可复现 | replay hash 一致率 | S1–S6 | 100% | 任一不一致且无法解释 |
| C7 | 机构 stop-order 能在 ≤ 1 个控制周期内触发安全停止 | 停止延迟 | S6 | ≤ 1 ms（控制层） | 停止延迟 > 10 ms |

| 场景 | 目的 | 设置 | 关键观测 |

### 5.3 仪器与数据采集

- 机器人本体：关节位置/速度/力矩 @1 kHz；末端六维力/力矩 @1 kHz；触觉阵列 @1 kHz。
- 外部真值：光学动捕（≥ 200 Hz）标定末端位姿与接触点；独立力台。
- 计算与网络：控制环 CPU 时间戳、调度延迟、丢帧计数；网络抓包。
- 审计：哈希链日志（每条证书签发/拒绝/失效/stop-order 追加）；时钟同步（PTP）。
- 安全：硬件 E-stop、软件看门狗、门触发安全停止、独立安全 PLC。
- 复现：容器镜像 digest、随机种子、配置哈希、数据清单哈希。

### 5.4 判定标准与统计

- 每个阈值预注册；二项指标用 Clopper–Pearson 95% 区间；延迟用 P50/P99/P99.9 + 自助法置信区间。
- 安全违例采用非劣效检验（margin = 1 个百分点）；C1 采用单侧上界检验。
- 所有原始数据与 replay manifest 随演示包发布；独立见证人签署 hash。

### 5.6 复现、见证与 kill switch

- **replay_hash = SHA256(canonical_manifest)**，manifest 含：容器 digest、代码 commit、配置、随机种子、场景脚本、数据清单、仪器校准记录。
- **独立见证**：见证人持有自己的签名密钥，对 manifest hash 与现场日志根哈希签名；与开发方密钥分离。
- **kill switch**：硬件 E-stop 优先；软件看门狗在 L0 门失败/超时/丢帧超阈值时触发安全停止；安全停止定义为进入阻抗软化 + 重力补偿 + 抱闸，停止延迟目标 ≤ 1 ms（控制层），最坏 ≤ 10 ms。
- **停止后**：审计链记录触发原因、门、时间戳；不允许自动恢复，需人工确认。

### 5.7 伦理审查材料清单

1. 研究协议与目的、部署 scope（任务/对象/环境/人机共处模式/法域）。
2. 风险评估与缓解（含双重用途评估）。
3. 知情同意/旁观者告知方案；人类干预与退出通道。
4. 数据治理计划（最小化、脱敏、存储期限、跨境、访问控制）。
5. 监督与问责计划（责任人、RACI、事件上报、申诉与补救）。
6. 条件清单与复审触发器（漂移阈值、事故、scope 变更）。
7. 撤回与暂停程序；证书有效期与续期规则。

## 6. 已知风险与缓解（增量更新）

| 风险编号 | 描述 | 严重度 | 缓解措施 | 剩余风险 |
|---|---|---|---|---|
| R19–R52 | v1~v4 全部既有风险 | — | 随原版继承；R46~R51 仍适用 | 见既有表 |
| R53 | **伦理审查 rubber-stamping**（委员会走过场，证书纸面合规但实质未审） | **极高** | 随机深度审计；异议与 stop-order 通道；独立见证；短有效期强制复审；审查质量元评估 | 社会过程无法被形式化保证 |
| R54 | **stale certificate / 治理缺口**（慢时标证书未过期但分布已漂移） | **极高** | 漂移监控多信号冗余；D_drift 超界自动失效；最长有效期 H_max；事故触发复审 | 隐蔽/对抗漂移可能漏检 |
| R55 | **演示过拟合/挑选**（场景与阈值被挑选以通过） | 高 | claim 预注册；held-out 场景；红队；replay hash；见证人独立 | 开放世界覆盖本质上不完备 |

| R57 | **责任稀释**（多方审查导致无人负责） | 中 | 具名签署人 + RACI；审计链；单一安全官一票暂停 | 组织政治可能削弱问责 |

## 7. 本轮最大风险（最终确认）

**一句话**：**伦理审查与演示方案都是慢时标、可被「盖章」形式化通过的治理证据，存在 rubber-stamping 与 stale-certificate 风险**——纸面合规、证书未过期，但运行分布或人类价值已漂移，系统仍在「合法」地做错事。
