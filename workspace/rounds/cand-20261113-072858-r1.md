# 第 66 轮（承接第 65 轮「VISTA 视觉知情安全时序归因闭环」IP-214~223；灵感循环第 1 轮；本轮灵感：「奖励设计」×「故障诊断」）

> 第 65 轮把「几何可证伪」升级为「故障可归因」，其自述的最大风险是 A88：故障被假定为**有限已知集合中的一员**，且视觉与几何的失效**相互独立**；未知复合故障会被 FIR 强行归入最近假设、只膨胀错误的球，系统反而因「已经归因」更自信。但沿 A88 再往上游追一步，会撞见一个更尴尬、此前从未被正面处理的缺口：**VISTA 的整条归因—认证链条，与真正塑造策略行为的奖励信号是脱钩的。** 诊断只是「观察者的旁路」，而机器人的动作由奖励的梯度决定。由此出现三个互相咬合的漏洞：
>
> **(i) 诊断需要激励，但策略没有理由去激励。** 引理 7（三阶段可辨识性）默认零力窗、轻触、加载都被激励过；可对一个被奖励优化的策略，绕开零力窗能省时间、避免加载能降风险，于是 S 的列自行坍缩、κ_fi→0——**VISTA 的前提被策略自己优化掉了**。
>
> **(ii) 诊断一旦进入奖励，就会被游戏。** 最自然的做法是把互信息 I(ℋ;ρ) 加进奖励；但策略会立刻学会制造不可预测的残差（乱碰、抖动、故意触发软接触）来抬高熵增。这正是「为惊讶付费，就得到制造惊讶的策略」——**故障诊断版的 reward hacking**。
>
> **(iii) 故障是动作与奖励之间的混淆变量。** 被 spoof 的相机能让「目标已达成」看起来为真，力偏置能让「轻触」看起来像「重压」。策略获得的不是任务能力，而是**利用故障套利**的能力。
>
> 本轮因此不问「哪一层坏了」，而问：
>
> **奖励该为哪些「被诊断证实」的行为付费？怎样设计奖励，使诚实诊断、主动激励、及时修复成为策略的最优策略，而不是让它靠隐藏 / 制造 / 利用故障获利？**
>
> 核心命题：**把「故障诊断」变成奖励的审计器，把「奖励设计」变成诊断的激励器。奖励只支付「可归因于智能体、且通过证书审计」的部分；诊断信息本身用严格 proper scoring rule 预注册付费；二者在故障感知奖励机上耦合，使「诚实」成为占优策略。**

## 0. 直觉与动机

**灵感 1（奖励设计 → 奖励是策略唯一的引力场，诊断不进奖励就不会被激励）**
直觉：VISTA 把 FIR 当成一个外部观察者，好像机器人「顺便」就会走出零力窗、轻触、加载。但对一个被奖励优化的策略，**任何不产生任务收益的动作都会被优化掉**。诊断不是免费品：它要么消耗任务进度，要么消耗安全预算。因此必须把「可辨识性」当成一种**需要付费的生产要素**，而不是一个免费的自然现象。反过来，一旦付费，就必须防止策略为了报酬而「表演诊断」。

**灵感 2（奖励设计 → 不要为「信息量」付费，要为「预测得准」付费）**
直觉：直接为互信息付费会被 hack：策略可以制造不可预测的残差来抬高熵。奖励设计的老教训是：要 elicitation 真实信念，就用**严格 proper scoring rule**。正确做法是**预注册**：策略先承诺「下一个固定窗口的残差分布 p̂」，再按对数分数 log p̂(ρ_obs) 结算。想拿分，必须**先学会读懂故障再探测**，而不是先把世界搞乱。

**灵感 3（故障诊断 → 故障是动作与奖励之间的混淆变量）**
直觉：在因果图里，故障 U 同时指向观测 O 与奖励 R，于是 A→R 的因果效应被 U 混淆。策略可以选择「利用故障」而非「完成任务」。信用分配必须反事实：只支付「在无故障反事实下同样会出现」的那部分奖励，把故障带来的差记成**故障负债**，而不是奖金。这不是惩罚，而是**不让故障替智能体付账**。

**灵感 4（奖励设计 → 奖励机把诊断状态变成任务的一部分）**
直觉：奖励机能把非马尔可夫任务写成有限自动机，让策略「知道自己在哪个阶段」。把 VISTA 的故障后验离散成 {Nominal, Suspect, Audit, Repair, Degraded}，让状态决定**发什么奖励、扣什么成本**：Suspect 只发诊断奖励、不发任务奖励；Audit 只发有限探索预算；Repair 发有上限的修复奖励；Degraded 不发任务奖励。策略于是自然愿意「先诊断、再修复、再恢复」。

**灵感 5（故障诊断 → 奖励通道本身也是会坏的传感器）**
直觉：既然 F/T 会偏、相机骗人，那么**奖励模型也会错、也会被 hack**。把 H_reward 加入故障假设集：奖励代理与真实目标不一致、奖励依赖的传感器被污染、奖励被日志重放 / 伪造。诊断不仅诊断物理栈，也**诊断奖励本身**。这是本轮的反身一步：奖励设计产出诊断，诊断反过来审计奖励设计。

**灵感 6（合流 → AUDIT：Audited Utility with Diagnosis-Incentivized Truthfulness，诊断激励真实性下的审计式效用）**
闭环：VISTA 的 FIR 后验 → 故障感知奖励机 FRM → 预注册诊断奖励 PDR → 故障不变任务奖励 FIRew → 反事实信用记账 CCA → 诊断信息定价 RDP → 奖励通道诊断 RAD → 开放集审计态 OSR → 奖励审计账本 AL → 奖励对抗认证 AIC-A → J_audit。VISTA 问「谁坏了、该膨胀哪个球」；AUDIT 问「**这条奖励凭什么发、发给谁、发多少，策略有没有动机把故障藏起来**」。

**灵感 7（VISTA 组件的原位升级）**
- **FIR → FRM**：故障后验不再只驱动「膨胀哪个球」，还驱动奖励机状态与发奖门控。
- **AFA → PDR + RDP**：探针选择从「最大化互信息」升级为「最大化预注册对数分数」，并用影子价格约束过度探测。
- **CSC → 奖励归属前缀**：只对「已执行且通过认证」的 k* 步发奖，未兑现的动作不计酬。
- **RSC-V → 故障负债**：把被归因故障造成的奖励偏差记入账本，而不是并入不确定球。
- **WCV-V → 风险预算**：CMDP 中与奖励预算联合求解。
- **CSP-V → FRM 感知规划**：把 `audit` / `repair` 作为元技能加入技能图。
- **AIC-V → AIC-A**：干扰集新增奖励投毒、代理游戏、目标 spoof、故障养殖、账本重放。
- **J_vista → J_audit**：证书增加 FRM 状态、预注册哈希、反事实基线、不变量版本、账本根、故障负债。

## 1. 形式化定义（增量：定义 233–248）

- **定义 233（AUDIT 闭环）**：AUDIT = (VISTA, FRM, PDR, FIRew, CCA, RDP, RAD, OSR, AL, AIC-A, J_audit)。定位：VISTA 的「奖励—诊断耦合」升级。不变式：**奖励建模、预注册、反事实记账、审计与发放只在语义流 / 离线；实时流只做 FRM 状态转移、发奖门控、前缀执行与早停，零学习写操作。**
- **定义 234（故障感知奖励机 FRM）**：FRM=(Q,q₀,Σ,δ,Ω,ρ,R)。Q={N 正常, S 可疑, A 审计, R 修复, D 降级}；Σ 由 FIR 后验、证书状态、负债余额与新颖度触发；ρ:Q→2^AP 为状态许可，R:Q×Q×AP⇀ℝ 为**状态门控奖励**：N 发任务奖励+有界诊断奖励，S 只发诊断奖励，A 只发探索预算，R 发有上限修复奖励，D 发 0。奖励在「证书未 Valid」时**一律不可领取**（⊤ gate）。
- **定义 235（预注册诊断奖励 PDR）**：在固定审计窗 w（由调度器决定、策略不可选）上，策略先输出预测密度 p̂_t(ρ_{t+1:t+w})，执行后按有界对数分数 `S(p̂,ρ)=log clip(p̂(ρ),ε)` 结算：`r_diag=λ_info·(S(p̂,ρ_obs)−S(p_ref,ρ_obs))`。S 严格 proper：`E_{ρ∼p}[S(p,ρ)]≥E_{ρ∼p}[S(q,ρ)]`。诊断奖励总量受预算 `Σ r_diag≤B_info` 约束。
- **定义 236（诊断信息影子价格与联合预算）**：CMDP：`max E[Σ_t (r_task+r_diag−c_risk)]` s.t. `E[Σ c_risk]≤B_risk`、`E[Σ r_diag]≤B_info`、`E[Σ c_time]≤B_time`。Lagrange 乘子 λ_risk、λ_info 为影子价格；λ_info 由「边际信息 = 边际风险」对偶条件在线调整：`λ_info ∂I/∂a = λ_risk ∂c_risk/∂a`。
- **定义 237（故障不变任务奖励 FIRew）**：设故障环境集 E（由 FIR 标签给出），特征 Φ 满足跨环境不变性 `P(Φ(O)|A,U=u)=P(Φ(O)|A,u₀) ∀u∈E`。任务奖励 `r_inv=g(Φ(O))` 只用不变量；训练用 IRM 风险 `Σ_e R_e(g)` + 惩罚 `Σ_e ‖∇_{e}R_e(g)‖²`。不变性未覆盖的环境触发 OSR。
- **定义 238（反事实信用与故障负债 CCA）**：结构因果模型 M：`O=f_O(A,U,Z_O)`、`R_obs=f_R(A,U,Z_R)`。可归因奖励 `r_attr(a)=E_Z[R|do(A=a,U=u₀)]`；故障负债 `L_f=R_obs−r_attr`，只在账本中记账，**不进入策略奖励**。实际用 `r̂_attr=Σ_u P(u|ρ)·E_Z[R|do(A=a,U=u)]` 的加权差估计，M 误设的偏差计入审计置信区间。
- **定义 239（奖励审计账本 AL）**：append-only 哈希链，条目 `e_i=(claim_i, evidence_i, J_audit_i, adjudication_i, h_{i-1})`。要求：每笔奖励对应唯一证据、不可双花、可重放校验；账本根 `ledger_root` 进入证书。审计器可离线重算任意历史条目。
- **定义 240（奖励通道故障假设 H_reward 与 RAD）**：ℋ_A=ℋ_VISTA∪{H_reward}，H_reward 含「代理目标错设、奖励传感器被污染、奖励模型被投毒、奖励日志重放 / 伪造」。证据 `ρ_R=[预测奖励残差, 多源奖励分歧, 反事实结果核验, 人类偏好查询, 账本一致性]`；后验 `P(H|ρ_R)`。归因到 H_reward 时冻结任务奖励、进入 Audit、请求外部核验。
- **定义 241（修复奖励上限与故障养殖）**：修复奖励 `r_repair≤c_repair`，且 `c_repair<c_induce+c_detect`（诱发故障的成本+被检出成本）。故障养殖增益 `G_farm=E[Σ(r_repair+r_diag)−c_induce]`，机制要求 `G_farm<0`。
- **定义 242（开放集审计态 OSR 与奖励冻结）**：新颖度 `ν=H(P(ℋ|ρ))+d_ρ(ρ,𝒟_cal)`；`ν>ν_max` 或后验不集中 → FRM 进入 A 态，任务奖励冻结，只允许有风险预算的**奖励无关探索**；未知故障因此**无法通过继续执行获利**。
- **定义 243（激励相容与偏离增益）**：策略报告其诊断后验 p̂ 并选择动作。偏离集 Δ={隐藏故障、诱发故障、伪造证据、利用故障、过度探测、伪造奖励}。机制 IC ⇔ 对任意 π′∈Δ，`G(π′|π)=E[Σr_{π′}]−E[Σr_π]≤0`。
- **定义 244（诊断—奖励对偶与可套利子空间）**：VISTA 签名矩阵 S（E[ρ|θ]=Sθ）与奖励敏感度 `B=∂E[R_obs]/∂θ`。不可检测故障子空间 `N(S)=ker S`；**不可检测套利** `G_undetect=max_{θ∈N(S),‖θ‖≤1} Bθ`。若 S 列满秩则 N(S)={0}、G_undetect=0。一般地 `G_undetect≤‖P_{N(S)}Bᵀ‖`。
- **定义 245（AIC-A 奖励对抗认证）**：ℰ_A=ℰ_V×ℰ_R，ℰ_R 含奖励投毒、代理目标错设、目标传感器 spoof、故障养殖策略、预注册后改窗、账本重放 / 双花、奖励延迟 / 非平稳。红队策略集 Π_hack 显式优化 `G_hack`；认证要求 `max_{π∈Π_hack} G_hack≤0`（或小于可接受阈值）且审计可检出。
- **定义 246（AUDIT 证书 J_audit）**：J_audit=(J_vista, frm_state, payout, diag_score, prereg_hash, invariant_ver, counterfactual_hash, fault_liability, ledger_root, reward_channel_state, aic_a_ver)。Valid ⇔ Valid(J_vista) ∧ FRM 状态许可 ∧ payout≤审计后可归因奖励 ∧ 无未决欺诈标记 ∧ 账本一致 ∧ AIC-A 通过。
- **定义 247（AUDIT 闭环算子）**：语义流 [VISTA 全链→FIR 后验→FRM 状态→PDR 预注册→FIRew/CCA→RDP 定价→RAD→AL 记账→CSP-V 块规划→CSC 认证前缀→AIC-A]；实时流 [FRM 门控→发奖前缀执行→CSC 早停→账本追加→J_audit 构建]。
- **定义 248（审计式奖励均衡）**：策略 π* 与机制 (FRM,PDR,FIRew,CCA,AL) 构成均衡，若 π* 在预算约束下最大化期望审计后效用，且诚实报告 + 及时修复 + 按需激励是 π* 的一个子博弈完美均衡路径。

## 2. 关键算法骨架

```python
# FRM + PDR + 发奖门控（语义流决策，实时流只执行）
state = frm.transition(post, cert, liability, novelty)      # N/S/A/R/D
p_hat = policy.preregister(obs, state, window=W)           # 预注册，窗口锁定
# ... 执行一个认证前缀 ...
S = log_score(p_hat, rho_obs); r_diag = lambda_info * (S - S_ref)
r_task = invariant_reward(Phi(obs))                         # 只用不变量
r_attr = cca.attributable(obs, action, post)                # 反事实信用
liability += observed_reward - r_attr
payout = frm.gate(state, r_task + r_diag) if cert.valid else 0.0
ledger.append(claim=payout, evidence=(p_hat, rho_obs, r_attr), j_audit=J)

# 修复奖励上限与开放集冻结
if state == 'S' or post.entropy > H_MAX:
    r_task = 0.0                                            # 不诊断就不给任务奖励
if state == 'A':
    r_diag = 0.0; allow_only(reward_free_exploration)        # 未知故障不能靠继续执行获利
if state == 'R':
    payout = min(c_repair, repair_credit())                 # 防故障养殖
```

## 3. 保证概要与推导要点（完整推导见产物区）

- **引理 9（proper 诊断奖励抗「制造惊讶」）**：严格 proper 的 S 使真实预测 p 的期望分数不低于任何 q；有界对数分数下，任何只增大结果熵、不增大可预测性的动作，期望诊断奖励不增。故 PDR 不能靠制造混乱刷分。
- **引理 10（故障养殖无利可图）**：若 `c_repair<c_induce+c_detect` 且总诊断预算有限，则 `G_farm<0`；策略不会为了修复奖励而主动制造故障。
- **引理 11（故障不变奖励 ⇒ 零故障套利）**：若 r_task 只依赖跨故障环境不变的特征 Φ，则对任意 u，`E[r_task|do(U=u),A=a]=E[r_task|do(U=u₀),A=a]`，故障不能产生正奖励差；观测差全部记入 L_f。
- **定理 9（激励相容审计机制）**：在 A100–A106（proper PDR、修复上限、故障不变任务奖励、证书门控发奖、账本完备、开放集冻结、AIC-A 覆盖）下，诚实诊断 + 及时修复 + 恢复是子博弈完美均衡；任意 Δ 中偏离的增益 ≤0。证明用 one-shot deviation principle + 引理 9–11。
- **定理 10（诊断—奖励对偶：κ_fi 界定不可检测套利）**：`G_undetect=‖P_{ker S}Bᵀ‖≤‖B‖·(1/κ_fi 的相应界)`；当 S 列满秩（VISTA 引理 7）时 G_undetect=0。即**提高可辨识裕度等价于提高奖励完整性**：VISTA 的 κ_fi 从「故障能不能分清」升级为「奖励能不能被套利」。
- **命题（AUDIT 相对 VISTA 的收益）**：VISTA 在故障下支付完整观测奖励，套利上界为 Bθ；AUDIT 支付 r_attr，套利项被 L_f 吸收，并因 PDR 恢复激励而使 κ_fi 回升——「防套利」与「保可辨识」互相加强。
- **实时性**：奖励门控、FRM 转移、账本追加、前缀派发在实时流（<0.3ms）；PDR 打分、CCA、RAD、AIC-A 全在语义流；目标 ≤2.6ms（A107，需窗口证据复用 VISTA 的 ρ）。

## 2. 形式化定义（完整版）

**定义 233（AUDIT 闭环）** AUDIT 是 VISTA 的「奖励—诊断耦合」升级：保留 VISTA 的语义流 ∘ 实时流骨架与全部安全证书，新增 FRM（故障感知奖励机）、PDR（预注册诊断奖励）、FIRew（故障不变任务奖励）、CCA（反事实信用记账）、RDP（风险—诊断定价）、RAD（奖励通道诊断）、OSR（开放集冻结）、AL（审计账本）、AIC-A（奖励对抗认证），并把 J_vista 升级为 J_audit。不变式：**奖励建模、预注册、反事实记账、审计与发放只在语义流 / 离线线程；实时路径只做 FRM 状态转移、发奖门控、认证前缀执行、早停与账本追加，零学习写操作。**

**定义 234（故障感知奖励机 FRM）** FRM=(Q,q₀,Σ,δ,Ω,ρ,R)。状态 `Q={N,S,A,R,D}`：
- **N（正常）**：Valid(J_audit) 且 FIR 后验集中于 H0 且新颖度低；发放任务奖励 + 有界诊断奖励。
- **S（可疑）**：后验最大概率 `max_H P(H|ρ)<1−δ_fi`（VISTA ambiguous）或存在未处理负债；**只发诊断奖励，不发任务奖励**。
- **A（审计）**：`ν>ν_max` 或 H_reward 被归因；任务奖励冻结，只允许奖励无关探索（预算内）。
- **R（修复）**：已归因且执行重标定 / 柔顺 / 重定位；发有上限修复奖励 `r_repair≤c_repair`。
- **D（降级）**：安全停机 / 合规撤退；发 0。

转移 `δ:Q×Σ→Q` 由 FIR 后验、证书状态、负债余额、新颖度与预算残量触发。奖励门控 `R(q,q',AP)`：**若 J_audit 不 Valid，任何奖励不可领取（⊤ gate）**。这使状态机不仅是「惩罚」，而是把诊断变成任务本身的阶段。

**定义 235（预注册诊断奖励 PDR）** 在固定审计窗 `w`（由调度器决定，策略不可选择窗口，防止「事后挑窗口」）上，策略在**执行前**输出预测密度 `p̂_t(ρ_{t+1:t+w})`，执行后按有界对数分数
`S(p̂,ρ_obs)=log clip(p̂(ρ_obs),ε)`
结算：
`r_diag = λ_info · (S(p̂,ρ_obs) − S(p_ref,ρ_obs))`，
其中 `p_ref` 为离线标定得到的参考预测。S 严格 proper：
`E_{ρ∼p}[S(p,ρ)] ≥ E_{ρ∼p}[S(q,ρ)]`，等号仅在 q=p。
诊断奖励总预算 `Σ_t r_diag ≤ B_info`。**动机**：为「预测得准」付费，而不是为「惊讶」付费；想拿分必须先学会读懂故障，再设计探测。

**定义 236（诊断信息影子价格与联合预算 RDP）** 策略在 CMDP 中求解
`max_π E[Σ_t (r_task + r_diag − c_risk)]`
s.t. `E[Σ c_risk]≤B_risk`，`E[Σ r_diag]≤B_info`，`E[Σ c_time]≤B_time`。
对偶乘子 λ_info、λ_risk、λ_time 为影子价格。λ_info 在线更新，使边际条件
`λ_info · ∂E[I]/∂a = λ_risk · ∂E[c_risk]/∂a + λ_time · ∂E[c_time]/∂a`
成立。**这替代了 VISTA 固定阈值 δ_fi 的硬开关**：信息值随风险价格连续变化，易损物体上 λ_risk 高 → 自动退化为视觉-only / null_test。

**定义 237（故障不变任务奖励 FIRew）** 设故障环境集 `E`（由 FIR 的 H 标签给出）。特征 `Φ(O)` 满足跨环境不变性：
`P(Φ(O)|A=a,U=u)=P(Φ(O)|A=a,U=u₀)`，`∀u∈E`。
任务奖励 `r_inv=g(Φ(O))` 只依赖不变量，训练风险为
`R_IRM(g)=Σ_{e∈E} R_e(g) + β Σ_{e∈E} ‖∇_{w|w=1}R_e(w∘g)‖²`。
不变性未覆盖的环境由 OSR 处理（定义 242）。**这不是「换一个奖励函数」，而是从奖励中删掉所有故障可影响的自由度**。

**定义 238（反事实信用与故障负债 CCA）** 结构因果模型 M：
`O=f_O(A,U,Z_O)`，`R_obs=f_R(A,U,Z_R)`，`A=π(O_<t)`。
可归因奖励
`r_attr(a)=E_Z[R | do(A=a, U=u₀)]`；
故障负债
`L_f = R_obs − r_attr`。
**只有 r_attr 进入策略奖励，L_f 只进入账本**。实践中用后验加权反事实估计
`r̂_attr(a)=Σ_u P(u|ρ)·E_Z[R|do(A=a,U=u)] − Σ_u P(u|ρ)·E_Z[R|do(A=a,U=u₀)]` 的差；
M 的误设偏差写成审计置信区间 `±ε_scm`，若 `|L_f|>τ_L` 则触发 RAD（奖励通道诊断）。

**定义 239（奖励审计账本 AL）** 账本为 append-only 哈希链：
`e_i=(claim_i, evidence_i, J_audit_i, adjudication_i, h_{i-1})`，`h_i=Hash(e_i)`。
性质：(i) **唯一证据**：每个 claim 对应唯一 `(prereg_hash, ρ_obs, r_attr)`；(ii) **不可双花**：同一证据不能重复领取；(iii) **可重放**：审计器可用历史证据离线重算任意条目；(iv) **不可否认**：`ledger_root` 写入 J_audit。账本使「奖励」从不可验证的标量变成可审计的对象。

**定义 240（奖励通道故障假设 H_reward 与 RAD）** 扩展假设集
`ℋ_A = ℋ_VISTA ∪ {H_reward}`，
H_reward 包含：代理目标错设、奖励传感器被污染、奖励模型被投毒、奖励日志重放 / 伪造。证据
`ρ_R=[预测奖励残差, 多源奖励分歧(环境/人类/自评), 反事实结果核验, 人类偏好查询, 账本一致性]`；
后验 `P(H|ρ_R)`。归因到 H_reward 时：冻结任务奖励、进入 A 态、请求外部核验、把奖励版本降权。**这使「奖励设计」自身也进入故障诊断的覆盖范围。**

**定义 241（修复奖励上限与故障养殖）** 修复奖励满足 `r_repair≤c_repair`，且
`c_repair < c_induce + c_detect`。
故障养殖增益
`G_farm = E[Σ_t (r_repair + r_diag) − c_induce]`。
机制要求 `G_farm<0`。诊断预算有限（`Σ r_diag≤B_info`）进一步封顶养殖收益，防止「先制造故障再领修复与诊断双份奖励」。

**定义 242（开放集审计态 OSR 与奖励冻结）** 新颖度
`ν = H(P(ℋ|ρ)) + d_ρ(ρ, 𝒟_cal)`，
其中 `d_ρ` 为到标定签名分布的稳健距离。若 `ν>ν_max` 或后验不集中，FRM→A 态：**任务奖励冻结**，只允许有风险预算的**奖励无关探索**（reward-free exploration），并以 e-process 监测新颖度是否回落。由于继续执行不产生任务奖励，**未知故障无法通过「硬着头皮干」获利**——这是对 VISTA A88 的激励层回答：不能保证归因正确，但能保证「归因不明时没有套利动机」。

**定义 243（激励相容与偏离增益）** 策略报告诊断后验 p̂ 并选择动作。偏离集
`Δ={hide 隐藏故障, induce 诱发故障, fake 伪造证据, exploit 利用故障, overprobe 过度探测, forge 伪造奖励}`。
机制激励相容（IC）⇔ 对任意 `π'∈Δ`，
`G(π'|π) = E[Σ r_{π'}] − E[Σ r_π] ≤ 0`。
`satisfies IC` 是 J_audit 的必填审计结论，而不是训练时的软约束。

**定义 244（诊断—奖励对偶与可套利子空间）** 沿用 VISTA 线性化 `E[ρ|θ]=Sθ`，定义奖励敏感度 `B=∂E[R_obs]/∂θ`。**不可检测故障子空间** `N(S)=ker S`；**不可检测套利**
`G_undetect = max_{θ∈N(S),‖θ‖≤1} Bθ = ‖P_{N(S)}Bᵀ‖`。
若 S 列满秩（VISTA 引理 7），则 `N(S)={0}`、`G_undetect=0`：**凡是能让奖励变化的故障，都必然在签名上留下可检测痕迹**——这正是「诊断可辨识」与「奖励不可套利」的对偶。

**定义 245（AIC-A 奖励对抗认证）** 干扰集
`ℰ_A = ℰ_V × ℰ_R`，
`ℰ_R` 含奖励投毒、代理目标错设、目标传感器 spoof、故障养殖策略、预注册后改窗 / 挑窗、账本重放 / 双花、奖励延迟与非平稳。红队策略集
`Π_hack = {π: max E[G_hack]}`，
其中 `G_hack` 为任一定义 243 偏离的增益。认证要求
`max_{π∈Π_hack} G_hack ≤ ε_hack`（目标为 0），且审计器对每种攻击给出可检出性下界。n_cert 由 128 升至 192，其中 64 用于奖励 / 账本 / 激励攻击。

**定义 246（AUDIT 证书 J_audit）** `J_audit=(J_vista, frm_state, payout, diag_score, prereg_hash, invariant_ver, counterfactual_hash, fault_liability, ledger_root, reward_channel_state, aic_a_ver)`。验证规则：
`Valid(J_audit) ⇔ Valid(J_vista) ∧ FRM 状态许可 ∧ payout ≤ 审计后可归因奖励 ∧ 无未决欺诈标记 ∧ 账本根一致 ∧ aic_a_ver 为当前版本`。
审计链回答四个新问题：**为什么发这笔奖励（r_attr / L_f）、为什么现在发（FRM 状态）、诊断分数是否预注册（prereg_hash）、奖励通道本身是否健康（reward_channel_state）**。

**定义 247（AUDIT 闭环算子）** 语义流：
`[LiDAR→LSF→USR/MEL→VPG→ACH→VCV→FIR 归因→FRM 状态→PDR 预注册→FIRew/CCA→RDP 定价→RAD→AL 记账→WCV-V→CSP-V/TSL→CSC 认证前缀→AIC-A]`；
实时流：
`[锚点读→残差采集→FRM 门控→WCV-V 编译→π_σ 前缀派发→CSC 早停→账本追加→J_audit 构建]`。

**定义 248（审计式奖励均衡）** 策略 π* 与机制 `(FRM,PDR,FIRew,CCA,AL)` 构成审计式奖励均衡，若 π* 在预算约束下最大化期望**审计后效用**
`U_audit = E[Σ_t 1[Valid(J_audit)]·(r_attr + r_diag − c_risk)]`，
且「诚实报告 + 按需激励 + 及时修复 + 恢复」是 π* 的一个子博弈完美均衡路径。

## 3. 关键算法伪代码

### IP-224 FRM（故障感知奖励机）

```python
class FaultAwareRewardMachine:
    """FIR 后验 → 状态 → 发奖门控。奖励只在证书有效时发放。"""
    STATES = ('N', 'S', 'A', 'R', 'D')

    def __init__(self, delta_fi, nu_max, h_max, b_info, b_risk):
        self.delta_fi, self.nu_max, self.h_max = delta_fi, nu_max, h_max
        self.b_info, self.b_risk = b_info, b_risk
        self.used_info, self.used_risk = 0.0, 0.0

    def transition(self, post, cert, liability, novelty):
        h_star = max(post, key=post.get)
        ambiguous = post[h_star] < 1.0 - self.delta_fi
        if novelty > self.nu_max or cert['reward_channel'] == 'H_reward':
            return 'A'                                  # 冻结任务奖励，只做审计/探索
        if h_star != 'H0' and cert['repairable']:
            return 'R'                                  # 已归因且可修复
        if ambiguous or abs(liability) > self.liability_tol:
            return 'S'                                  # 只发诊断奖励
        if cert['degraded']:
            return 'D'
        return 'N'

    def gate(self, state, r_task, r_diag, cert):
        if not cert['valid']:
            return 0.0                                   # ⊤ gate：无效证书一律不发
        if state == 'D':
            return 0.0
        if state == 'A':
            return 0.0                                   # 只允许外部探索预算
        if state == 'S':
            return self._cap_info(r_diag)
        if state == 'R':
            return min(C_REPAIR, r_diag + r_task)        # 修复奖励上限
        return self._cap_info(r_diag) + r_task

    def _cap_info(self, r_diag):
        r = min(r_diag, max(0.0, self.b_info - self.used_info))
        self.used_info += r
        return r
```

### IP-225 PDR（预注册诊断奖励）

```python
class PreRegisteredDiagnosticReward:
    """执行前预注册 p_hat，执行后按有界对数分数结算。窗口由调度器锁定。"""
    def __init__(self, epsilon=1e-3, lam_info=1.0):
        self.eps, self.lam = epsilon, lam_info

    def preregister(self, policy, obs, window):
        self.window = window
        self.p_hat = policy.predict_signature_density(obs, window)
        return freeze_hash(self.p_hat, window)           # 写入账本，防事后改预测

    def settle(self, rho_obs, p_ref):
        s = np.log(np.clip(self.p_hat(rho_obs), self.eps, None))
        s_ref = np.log(np.clip(p_ref(rho_obs), self.eps, None))
        return self.lam * (s - s_ref)

    def reject_if_mutated(self, prereg_hash_now):
        return prereg_hash_now != self.prereg_hash       # 改窗/改预测即判欺诈
```

class FaultInvariantReward:
    def __init__(self, phi, g, beta=1.0):
        self.phi, self.g, self.beta = phi, g, beta

    def risk(self, envs):
        per_env = [env.risk(self.g, self.phi) for env in envs]
        penalty = sum(env.grad_penalty(self.g, self.phi) for env in envs)
        return sum(per_env) + self.beta * penalty

    def __call__(self, obs):
        return self.g(self.phi(obs))


class CounterfactualCredit:
    def __init__(self, scm, u0='nominal', tau_L=0.1):

    def attributable(self, obs, action, post):

        r_fault = sum(p * self.scm.expect_reward(action, u=u)

class RiskDiagnosisPricing:
    def __init__(self, b_risk, b_info, eta=0.05):
        self.b_risk, self.b_info, self.eta = b_risk, b_info, eta
        self.lam_risk, self.lam_info = 1.0, 1.0

    def update(self, info_gain, risk, time_cost, info_grad, risk_grad):
        # 对偶上升：边际信息 = 边际风险价格
        self.lam_risk = max(0.0, self.lam_risk + self.eta * (risk - self.b_risk))
        gap = self.lam_info * info_grad - self.lam_risk * risk_grad - time_cost
        self.lam_info = max(0.0, self.lam_info + self.eta * gap)
        return self.lam_info, self.lam_risk

class RewardChannelDiagnosis:
    HYP = ('H0', 'H_proxy', 'H_spoof', 'H_poison', 'H_replay')

    def evidence(self, r_pred, r_sources, cf_check, human_query, ledger_ok):

            abs(r_pred - np.median(r_sources)),          # 预测残差
            float(np.std(r_sources)),                    # 多源分歧
            float(cf_check['mismatch']),                 # 反事实结果核验
            float(human_query['disagree']),              # 人类偏好查询
            0.0 if ledger_ok else 1.0,                   # 账本一致性

        logp = {h: np.log(lik[h](rho_R) + 1e-12) + np.log(prior[h])
                for h in self.HYP}
        z = np.array(list(logp.values())); z -= z.max()
        post = {h: float(np.exp(v) / np.exp(z).sum()) for h, v in logp.items()}
        return post, max(post, key=post.get)

## 4. 推导

**引理 9（proper 诊断奖励抗「制造惊讶」）** 设结果分布为 p，策略报告 q。严格 proper 的对数分数满足
`E_{ρ∼p}[S(p,ρ)] ≥ E_{ρ∼p}[S(q,ρ)]`，等号仅当 q=p。
进一步，若某动作在结果上叠加与历史独立的噪声 η，使 `p' = p * η`，则最优可得分
`max_q E_{ρ∼p'}[S(q,ρ)] = E_{ρ∼p'}[S(p',ρ)] = −H(p') − E[log clip]`（有界对数分数），
由熵的凹性与独立卷积增熵，`H(p') ≥ H(p)`，故期望分数不增。因此「乱碰 / 抖动 / 故意触发软接触」这类只增熵、不增可预测性的动作，不能提高 PDR 收益；想拿高分的唯一途径是**提高对故障签名的可预测性**，即真正读懂故障。∎

**引理 10（故障养殖无利可图）** 策略若诱发一个可检出故障，收益为 `r_repair + r_diag`，成本为 `c_induce`，并以概率 q 被检出、付出 `c_detect`（含终止后续任务奖励的机会成本）。期望增益
`G_farm ≤ c_repair + B_info/n_fault − c_induce − q·c_detect`。
由 `c_repair < c_induce + c_detect` 与有限 `B_info`，当 `q` 与 `n_fault` 满足 `B_info/n_fault` 足够小（预算设计）时 `G_farm<0`。故修复与诊断的双份奖励不足以覆盖诱发成本。∎

**引理 11（故障不变奖励 ⇒ 零故障套利）** 若 `r_inv=g(Φ(O))` 且 Φ 在 `∀u∈E` 上满足定义 237 的不变性，则对任意动作 a，
`E[r_inv | do(U=u), A=a] = ∫ g(φ) P(φ|a,u) dφ = ∫ g(φ) P(φ|a,u₀) dφ = E[r_inv | do(U=u₀), A=a]`。
故故障 u 相对标称 u₀ 的期望奖励差为 0；任何观测到的奖励差只能来自非不变特征，而它已被排除在 r_inv 之外。由 CCA，这部分差被记为 L_f，不进入策略奖励。∎

**定理 9（激励相容的审计奖励机制）** 在假设 A100–A106 下：
- **A100** PDR 严格 proper 且有界，审计窗 w 由调度器锁定、策略不可选；
- **A101** 修复奖励上限满足 `c_repair < c_induce + c_detect`；
- **A102** 任务奖励只依赖故障不变特征，或 CCA 精确扣除故障负债；
- **A103** 所有发放由 Valid(J_audit) 门控，账本完备且唯一证据；
- **A104** 开放集下（`ν>ν_max` 或后验不集中）任务奖励冻结；
- **A105** AIC-A 红队覆盖偏离集 Δ，且 `max G_hack≤0`；
- **A106** FIR 后验校准，策略的私有信息是故障状态的充分统计量。
则「诚实报告 + 按需激励 + 及时修复 + 恢复」是子博弈完美均衡，且任意 `π'∈Δ` 的偏离增益 `G(π'|π)≤0`。
证明：对 Δ 逐一用 one-shot deviation。**hide**：FRM 使可疑/审计态不发任务奖励，隐藏只延迟恢复并损失折扣后的任务奖励；无收益。**induce**：引理 10，`G_farm<0`。**fake**：PDR 严格 proper 使伪造预测不能提高期望分数；账本唯一证据与预注册哈希使事后替换不可行；A105 给出可检出下界。**exploit**：引理 11，故障不产生奖励差；若产生，则必来自非不变特征，CCA 记 L_f 且不发放。**overprobe**：RDP 的 `B_info` 与影子价格使边际收益≤边际风险。**forge**：H_reward 诊断 + 账本根使伪造被检出或不可结算。有限折扣 MDP 中无有利的单步偏离 ⇒ 子博弈完美（one-shot deviation principle）。∎

**定理 10（诊断—奖励对偶：κ_fi 界定不可检测套利）** 设 `E[ρ|θ]=Sθ`、奖励敏感度 `B=∂E[R_obs]/∂θ`。一个故障 θ 若不可检测，则 `Sθ=0`，即 `θ∈ker S`。不可检测套利
`G_undetect = max_{θ∈ker S,‖θ‖≤1} Bθ = ‖P_{ker S}Bᵀ‖`。
若 `S` 列满秩（VISTA 引理 7 的三阶段可辨识条件），`ker S={0}`，故 `G_undetect=0`：**凡是能改变奖励的故障，必然在签名上可检测**。更一般地，`G_undetect ≤ ‖B‖·sin∠(B, row(S))`，其中 `row(S)` 为可检测方向张成的子空间。VISTA 的可辨识裕度 `κ_fi` 控制 `S` 的条件数：`κ_fi` 越大，可检测方向与噪声越可分，审计能覆盖的奖励敏感方向越多。于是 **VISTA 的「故障能不能分清」与 AUDIT 的「奖励能不能被套利」是同一个几何对象的两面**。∎

**命题（AUDIT 相对 VISTA 的收益）** VISTA 在故障 u 下支付完整观测奖励，期望套利项为 `Bθ`；AUDIT 支付 `r_attr`，套利项被 `L_f` 吸收，故期望套利降至 0（在引理 11 条件下）。同时，VISTA 的最优策略会绕开诊断激励，使 `κ_fi→0`；AUDIT 的 PDR 在 `B_info` 内为非零常数边际报酬，恢复零力窗/轻触/加载的激励，使 `κ_fi` 回升。二者相乘：**防套利（FIRew/CCA）与保可辨识（PDR）互相加强，而不是互相挤占预算。** ∎

**命题（开放集下的激励安全）** 当真实故障 `u*∉E`（未知）时，引理 11 的不变性不成立，CCA 可能低估 `L_f`。但 OSR 用 `ν` 将系统推入 A 态并冻结任务奖励；此时继续执行的期望任务奖励为 0，而任何利用未知故障获取奖励的行为都必须先通过 A 态的外部审计。故**未知故障下不保证归因正确，但保证没有「继续执行」的套利动机**——这是对 A88 的激励层补丁，而非统计层补丁。∎

## 7. 已知风险

**一句话**：AUDIT 的全部「诚实性」保证都条件于**存在可计算、可验证的故障不变任务奖励与反事实基线**；而真实任务效用不可观测、故障集开放，一旦不变量只近似成立或 SCM 误设，审计器就会为一笔**仍可被未知故障套利**的奖励盖上 Valid——更糟的是 proper scoring 与激励相容的外壳会给人「数学上已保证诚实」的错觉，使奖励审计器本身成为整个系统里唯一无人审计的单点故障。

**次级风险与缓解**：
1. **故障集开放，不变量覆盖不全**：真实故障 `u*∉E` 时引理 11 失效；缓解：OSR 冻结任务奖励 + 奖励无关探索 + 在线扩充环境集；不保证正确归因，只保证无套利动机。
2. **任务效用不可观测 / 代理错设**：`r_inv` 仍是代理；缓解：RAD 把 H_reward 纳入诊断、多源奖励交叉核验、人类偏好查询、定期红队审计代理。
3. **SCM 误设导致 `L_f` 有偏**：缓解：报告 `L_f` 的置信区间与敏感性分析；`|L_f|>τ_L` 触发审计而非直接扣款；用随机化对照（少量随机动作）估计因果效应。
4. **PDR 预注册窗被操纵**：策略可能选择「容易预测」的窗口；缓解：窗口由调度器锁定、哈希预注册、AIC-A 显式含 pick_window 攻击。
5. **修复奖励上限与任务奖励的相对尺度**：若修复奖励过高仍可能养殖；缓解：在线监控 `G_farm`，自适应下调 `c_repair`，并把修复次数计入账本。
6. **A 态冻结导致可用性下降**：未知故障频繁时机器人长期不领任务奖励、停在审计态；缓解：设置审计态时限与人工接管、奖励无关探索的收益上限、渐进式恢复。
7. **账本本身被攻击 / 存储增长**：缓解：哈希链 + 定期锚定到外部信任根、Merkle 压缩、抽样重放。
8. **激励相容只在均衡意义成立**：有限样本、函数逼近、非平稳下 SPNE 只是理想；缓解：把定理 9 当作设计目标而非运行时保证，持续红队与在线偏离检测。
