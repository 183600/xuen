# 第 8 轮 / 灵感循环 R3 · STF：视觉定位任务帧、4D 物体记忆、底盘是隐藏自由度

> 检索/复核日期：2026-10-24（UTC）。赛事身份确认不变：宇树科技 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「视觉定位」「移动底盘」「时空推理」。我先各自钉到本轮核实到的官方事实上，再合成主判断：**榜单头部的瓶颈已经不是语义，而是“状态与坐标系”：任务帧在哪、物体现在在哪、计划是否已经过期。给单模型加一层确定性的时空任务帧（STF），比再堆一个更大的 VLA 更划算；“移动底盘”在演示里几乎不动，它是一个隐藏自由度，正确用法是定位基座-桌面变换/任务化站姿，而不是学底盘移动。**

## 0. 本轮先核实：七个新事实

### 0.1 官方评分与赛道细则（新）

官方参赛手册（中英文版，[S2]）明确：

- 每个任务执行 **10 次独立运行**；10 次中包含 **5 种泛化类型，每种各出现 2 次**：位置、干扰物、桌面背景、未见物品、人为干扰。
- 通才赛道要求**单模型完成全部 32 个任务**；单任务调试通道不计分、不进榜。
- 实时榜单按 **32 个任务的总平均成功率**排序；成功率相同按**总平均步骤分**；仍相同则**提交日期较早**的模型靠前。
- **“所有任务须基于同一模型完成，不得混合使用多个模型一起进行测试，但对模型类型不作限制（World Model、VLA 均可）。”**

这条“单模型”约束比上一轮的理解更硬：它不只是“不能每个任务换一个模型”，而是“不能混合多个模型一起测试”。这直接影响我们能否把 SAM2/FoundationPose/RAFT-Stereo 之类的外部模型放进推理链——必须按确定性几何代码或“蒸馏进唯一 checkpoint”来设计。

### 0.2 数据集已全量发布，规模可精确核对

HF collection 的 32 个数据集（[S3]）逐个拉 `meta/info.json` 求和：

```text
32 tasks, 33,276 episodes, 18,282,246 frames, 30 fps, 169.3 h
每任务 969–1,533 条；HangCup 1,043 条 / 194,564 帧
HangCup lastModified = 2026-10-14T06:35:13Z
collection lastUpdated = 2026-09-11T08:31:57Z
```

四路相机为 `head_stereo_left/right` + `wrist_left/right`，480×640，AV1。每条 episode 约 3–10 秒（HangCup 中位 177 帧 ≈ 5.9s），远低于 180s 上限。上一轮“全量发布已落地”的判断成立，且现在可以给出精确总量。

### 0.3 数据集里有校准双目，但 API 不给你相机外参

`meta/info.json` 的 `camera_params`（[S4]）给出：

- `head_stereo`：左/右相机内参 `camera_matrix_left/right`、畸变、`R`、`T`；`T = [-58.25, -0.17, 0.58]` mm，基线 **58.25mm**，`rectified: true`。
- `wrist_left` / `wrist_right`：彩色相机内参、畸变。
- 观测里还有 `state_torso`、`state_d435`、`left/right_ee_pose_gripper_base/torso`；`state_d435` 的俯仰在约 0.16–0.20 rad 间变化，说明头部/相机有轻微俯仰。

但提交 API 的观测目录（[S5]）只有：四路 RGB、左右臂 7 维、左右 EE 位姿（base 系）、夹爪、`lower_body` 15 维、`observation.language`。**没有 `state_d435`，也没有 `state_torso`。** 所以评测时要把“相机系 → base 系”补回来：用 `lower_body` 的 waist yaw/roll/pitch + G1 URDF 做正向运动学，或用腕部相机 + EE 位姿做手眼标定。这是一个很具体的接口工程点，也是“视觉定位”能否落地的前提。

### 0.4 `action.pivot` 是共享动作，但演示里基座几乎不动

提交 API 的动作表（[S5]）包含共享键 `action.pivot` `[7]`；数据集里它的字段名是：

```text
vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height
```

同时还有 `action.base_command` `[4]`：`vx, vy, angle_z, height`。

我把 32 个任务的 `meta/stats.json` 全拉下来统计 `action.pivot`：

- 平面速度标准差：`vx std ≤ 3.4e-3`；yaw 标准差 `≤ 1.2e-2`。
- `height` 按任务基本固定，范围 0.61–0.74m；`pivot_4` 多数任务为 0.15，少数任务为 0.21 左右。
- 瞬时最大值偶尔出现 0.8 rad/s 或 0.4 m/s（更像初始化/重置瞬态），但 q99 基本回到 0。

结论：**32 个任务的演示都是“固定基座 + 任务化站姿”，没有可学习的底盘运动信号。** “移动底盘”在 UniBot 里是一个**隐藏自由度**：接口允许，但数据不教。把它当主路线去学 locomotion 是错的；正确用法是 (a) 把基座-桌面变换当未知量做视觉定位，(b) 用任务化站姿/高度做一次性调整，(c) 只有在调试槽确认 `action.pivot` 真的执行后，才考虑一次性 dock。

### 0.5 榜单和运行记录仍是占位

`leaderboard_data.json`（[S6]）的 `generated_from` 仍是 `gen_leaderboard.py`；8 个模型 ×32 任务 = 256 条 `task_metrics`；`runs.html` 是 256/256 占位，详情页写明“测试视频占位，后续可替换为真实视频文件”。榜单页现在能显示 8 行，但数据仍是脚本生成。

我不会用这些数字判断谁强谁弱。唯一可谨慎使用的结构是：8 个模型的“步骤分 − 成功率”平均约 **+8.6pp**（39.0−29.7、38.9−28.5、……、28.1−20.5），与“失败集中在后段步骤”一致；标“未核实”。8 个模型名都对应真实公开系统，下面按它们已发表的论文分析做法与瓶颈。

### 0.6 指令仍有 5 条英文复述，human 备注仍是逐任务剧本

上一轮已核实 `meta/tasks.parquet` 中每个任务有 5 条英文复述（`@` 分隔），SSG 的字符串匹配要覆盖 32×5=160 条。本轮不重复下载，但把它作为既定事实沿用。

`info.json` 的 `generalization` 仍有 `human_1_note`、`human_4_note`、`unseen_object_3`（[S4]）。编号含义官方未解释；但 0.1 的“5 类×2 次”意味着 human 轴每任务有 2 次，备注很可能就是这两次的剧本（例如 T27“叠了第二个之后拿下第二个”、T19“拉上拉链之后拉开”、T11“抓电池之后动绿色盒子”）。我们把它当“高价值扰动剧本”，不假设它是唯一评测条件。

### 0.7 任务页与提交接口没有破坏性变化

32 任务、32k/169h、任务视频与描述仍在（[S1]）；提交模板仍是 v2（2026-08-21），支持 `obs_delta_indices` 跳帧堆叠、`image_resize`、`action_chunk_size`、joint/ee 二选一、token 双处校验（[S5][S7]）。本轮没有发现接口字段删改。

## 1. 三个词，各自钉到事实上

### 1.1 视觉定位：桌面尺度的度量定位，不是房间 SLAM

UniBot 的任务全在桌面上，房间尺度 SLAM 没有用。真正缺的是**桌面尺度**的三级定位：

1. **桌面/任务帧**：用头部双目 + 机器人本体，拟合桌面平面，定义 `T_base_table`；再以桌面法向、机器人朝向定义稳定的 x/y 轴。这个帧是跨 episode、跨机器人、跨背景的“公共语言”。
2. **容器/目标 6D 位姿**：对架子、盘子、盒子、插排等，拟合平面/线段/包围盒，得到 `T_base_container`；这是放置的“目的地坐标系”。
3. **物体中心轨迹**：把桌面上方的高度簇/颜色簇/点云簇聚成物体，得到质心、PCA 朝向、可见性；这是时空推理的输入。

三级定位的精度不必到毫米：桌面帧 1cm/2°、容器帧 1–2cm/5°、物体质心 1cm 就足以支撑“最后 3 厘米”的伺服。双目基线 58mm、480×640、0.3–0.8m 工作距离，SGBM 的深度误差在毫米到厘米级；对桌面/容器足够，对透明试管/针筒不够，需要分桶回退。

**为什么这是机会**：平台已经把校准双目和相机参数放在数据集里，但 API 的观测名字是 `cam_left_high/cam_right_high`，不是 `head_stereo`；`camera_params` 也不在 API 文档里。多数基线把它当两路普通 RGB 用，等于把免费的 3D 传感器扔了。这是“接口考古”型创新点：不改模型，先把被忽略的几何信息接上。

### 1.2 移动底盘：演示里不动，接口里可动

0.4 已经给出事实：32 个任务的 `action.pivot` 平面运动几乎为零，height 是任务常量。这个事实有三个含义：

1. **不要学 locomotion**：演示没有信号；从零学底盘运动既无监督又高风险（G1 站立/轮式底盘的稳定性另说）。
2. **基座-桌面变换是未知量**：多机器人评测、不同桌面高度、不同摆放距离，都会让“base 系 EE 动作”的语义漂移。视觉定位 + 任务帧动作规范化（TFAC）可以在不移动底盘的情况下消除这个漂移。
3. **站姿是任务先验**：`height` 和 `pivot_4` 按任务不同（0.61–0.74m、0.15/0.21），说明“站多高、腰多俯”是任务相关的。可以用第一帧的桌面高度/物体距离，选一个任务化站姿；这比学底盘移动安全得多。

所以“移动底盘”在本轮的正确展开是：**把基座当“未知坐标系 + 一次性站姿”，而不是“连续控制自由度”。** 只有在调试槽确认 `action.pivot` 真的执行、且小角度/小位移稳定时，才做一次性 dock（视觉定位 → 转到 canonical 桌面相对位姿 → 重新定位 → 跑固定基座策略）。这是条件性押注，不是主线。

### 1.3 时空推理：物体中心 4D 记忆，不是 14B 视频世界模型

VLA 的上下文通常是“当前几帧图像 + 本体”；它没有“物体 A 在 t=3s 被人的手移到左边、现在被碗挡住、上次看到在 (x,y,z)”这种状态。帧堆叠不等于记忆：堆 8 帧只能让模型看到短时运动，不能维持物体身份、遮挡后的位置、被撤销的步骤。

2026 年的证据很一致：

- **OCC4M**（[S15]）：物体中心 4D 记忆 + 持久 track + 运动/包含关系；7 个仿真条件 350 episodes，记忆成功率 96.6%、端到端 88.9%，远高于全历史 VLM 基线；视角切换后仍 100%/98%。
- **RoboStream**（[S16]）：STF-Tokens 绑定 3D 几何 + 因果时空图记录动作触发的状态转移；长程 RLBench 90.5%，真实积木 44.4% vs 基线 11.1%。
- **SOMA**（[S17]）：可动头部扫描构建空间记忆，解决“目标出视野”的 VLA 失败。
- **RoboMME**（[S18]）：16 个记忆任务、14 种记忆增强 VLA 变体；结论是“没有一种记忆表示在所有任务都好”，感知记忆 + memory-as-modulator 平衡最好。
- **DREAM**（[S19]）：动态室内环境中人被移动目标后，用混合定位 + 动态时空语义记忆重新获取目标；长程成功率 40–60% → 55–70%。
- **Robust-TAMP**（[S20]）：决定“是否/何时/在哪里重规划”，在 14 个 MuJoCo 环境 + 5 个真实设置中 92.1%，比基线高 47.1pp。

反过来，**DreamZero**（[S10]）证明视频世界模型很强（环境/任务泛化 2× VLA），但它是 14B、实时 7Hz，且失败主要来自视频生成错误；对 UniBot 的 33k 数据、180s 预算、远程 API，这不是性价比最高的路线。**GigaBrain-0**（[S11]）则把世界模型当“离线数据引擎”（视频生成、real2real、view transfer），而不是运行时视频预测——这才是世界模型在 UniBot 里更合理的用法。

本轮的选择：**做物体中心的“任务级世界模型”（4D memory），不做像素级视频世界模型。** 它轻、可解释、可在 CPU 上跑，而且直接对准 human/position/occlusion 三个轴。

## 2. 榜单头部：方法很强，瓶颈很一致

> 先声明：榜单数字是占位，下面的“排名”只借用模型名，不用数字当结论。

| 占位排名 | 模型 | 已发表方法（要点） | 强项 | 对 UniBot 的瓶颈 |
|---|---|---|---|---|
| 1 | MolmoAct2 | Molmo2-ER 空间/具身 VLM + depth tokens + flow-matching action expert；自适应深度重预测 | 空间/具身推理、开放权重、真实部署 50.1% | 仍是 2D 轨迹/深度 token；无持久物体记忆；无任务帧动作规范化；深度重预测有延迟 |
| 2 | WALL-OSS-0.5 | 4B VLA、20+ 本体、每 epoch 100 万轨迹、梯度桥接 co-training | 预训练即有能力、微调后 60.5% task progress | 2D VLM 特征；精细双手/可变形弱（Pencil Case Packing 18.5%）；无度量 3D |
| 3 | DreamZero | 14B World-Action Model，视频+动作联合去噪，7Hz 实时 | 环境/任务零样本泛化 2× VLA | 视频生成错误主导失败；14B 算力/延迟；无物体身份/度量状态 |
| 4 | Spirit-v1.5 | 公开细节有限 | — | — |
| 5 | DM0 | 公开细节有限 | — | — |
| 6 | π0.5 | 异构 co-training + 高层语义子任务 + 低层动作 | 开放世界语义泛化、长程 | 精细操作弱：WALL-OSS 对比中 manipulation 35.0% vs 61.1% |
| 7 | GigaBrain-0 | 世界模型生成数据 + RGBD + 具身 CoT | 3D/数据引擎、视角/外观泛化 | 重；运行时仍以 2D/CoT 为主；无显式物体 track |
| 8 | GR00T N1.5 | 3B 双系统 VLA（VLM + DiT） | 通用、效率 | 2D；无显式状态/记忆 |

**共同瓶颈**（按对 UniBot 五轴的相关性排序）：

1. **度量 3D 精度**：多数模型靠 2D 语义特征 + 动作专家；桌面任务的“最后 3 厘米”需要度量几何。双目/深度是免费信号，但没被充分利用。
2. **持久状态**：没有物体中心 track；human 轴把物体移走/撤销后，模型容易继续执行旧计划。
3. **坐标系**：动作在 base 系表达；多机器人/不同桌面摆放会让同一像素目标对应不同 base 系坐标。
4. **精细双手/可变形**：拉链、笔袋、毛巾、针筒——WALL-OSS 的 Pencil Case 18.5% 就是证据。
5. **延迟/算力**：DreamZero 14B/7Hz；远程 API 还有网络延迟；180s 内要留重试预算。

**结论**：头部方案的“语义”已经很强，边际收益在**状态与坐标系**。这正好是 STF 的靶心。

## 3. 主判断：STF 是跨五轴的“状态正确性”杠杆

### 3.1 评分算术

```text
成功率 = P(所有步骤完成)                    # 32/32 任务的闸门都是终局步骤
步骤分 = Σ 步骤权重 × P(该步完成)          # 终局步骤合计 1275/3200 = 39.8%
排名   = 先总平均成功率，再总平均步骤分，再提交日期
```

上一轮已经抓全 32 个任务的 `score_steps`：终局步骤 39.8%，放置/插入/堆叠/闭合类约 59.7%。这一轮不重复抓，直接沿用。

### 3.2 十个 run、五条轴、320 个 episode

每个任务 10 次 = 5 类 ×2；32 任务 = **320 个计分 episode**。单比例的标准误：

```text
p = 0.30, N = 320 → SE = sqrt(0.30×0.70/320) ≈ 2.56pp
两次独立比较的 SE_diff ≈ sqrt(2×0.30×0.70/320) ≈ 3.62pp
80% 功效、α=0.05 双侧 → 需要约 2.8×SE_diff ≈ 10pp 的差异
```

也就是说：**+5pp 在 320 个独立 episode 上并不够显著；必须用配对任务/种子、任务级 bootstrap，或者把步骤分作为更敏感的第二指标。** 榜单上 1–2pp 的差距很可能只是噪声；不要为了 1–2pp 去过拟合单一轴。要押就押一个能在多轴同时起作用的机制。

### 3.3 STF 对五轴的作用

| 泛化轴 | 每任务次数 | STF 的作用 | 强度 |
|---|---:|---|---|
| 位置 | 2 | 物体初始位置变 → VTL/O4M 重新定位，SMP 用当前 3D 目标 | 强 |
| 人为干扰 | 2 | 物体被移动/步骤被撤销 → O4M 检测 relocation，STG 回滚重规划 | 强 |
| 桌面背景 | 2 | 背景变 → 度量几何/桌面帧不依赖外观；overlay 仍对齐 | 中强 |
| 干扰物 | 2 | 多物体 → O4M 用任务/SSG 选择相关物体，忽略 distractor | 中强 |
| 未见物品 | 2 | 外观变 → 物体中心几何/跟踪仍可用，但语义识别仍靠 VLA | 中 |

STF 不是“只修一个轴”，而是**在四个轴上同时提高状态正确率**；未见物品轴仍需要 VLA 的语义泛化，STF 只能保证“几何上找得到、跟得住”。

### 3.4 与 PILOT 的关系：输入状态 + 输出精度

- **PILOT（上一轮）**：终局放置是闸门；用 SSG/PGL/OPT/ICR/SVL 把“最后 3 厘米”做闭环。
- **STF（本轮）**：在“最后 3 厘米”之前，先保证“目标帧是当前的、物体是当前的、计划没过期”。
- 两者合起来是 **stateful terminal placement**：STF 管输入状态，PILOT 管输出精度。不是替代，是乘法。

一个粗略的失败分解（假设，需调试槽验证）：

```text
70% 失败
├─ 1/3 状态/坐标系错（物体移了、遮挡、目标帧错） → STF 攻
├─ 1/3 精度/放置错（姿态、释放、插入）           → PILOT/SMP/SVL 攻
└─ 1/3 抓取/接触错（滑、碰撞、力不够）           → NRB/数据/力控攻
```

如果 STF 能救回状态错的一半：`0.70 × 1/3 × 0.5 ≈ 11.7pp` 的理论上限；现实一点，+3–5pp 是合理目标；叠加 PILOT 的终局放置 +5–10pp，合计 +8–12pp 的潜力。这个数字必须用配对实验校准，不能当承诺。

### 3.5 “移动底盘”的负结果也是贡献

我们把 32 个任务的 pivot 统计做出来，发现演示里基座不动。这个负结果本身有价值：

- 它阻止我们把预算浪费在“学底盘移动”上；
- 它把“移动底盘”重解释为“基座-桌面变换未知 + 任务化站姿”，这才是 UniBot 的真实问题；
- 它给“视觉定位 + 动作帧规范化”提供了最强动机：**既然底盘不动，那就让动作不依赖底盘在哪。**

## 4. STF-GPR 轮廓

```text
语言(160 条复述) ──► SSG 评分步骤图（32 任务步骤+权重）──► 当前步骤 s_t
                                   │
  4 路 RGB + 本体 ──► VTL 视觉任务帧（双目度量定位）
                                   │  T_base_table / T_base_container / 物体候选
                                   ▼
                     O4M 物体中心 4D 记忆（ID/6D/可见性/速度/最后可见）
                                   │
                     STG 陈旧状态门控（预测 vs 观测；relocation/occlusion）
                                   │  触发回滚/重规划/重观测
                                   ▼
                     SMP 3D 放置锚点（槽位→3D 位姿→投影渲染）
                     OPT 少样本释放位姿（容器系统计）
                     ICR 检索上下文（关系键+相位键）
                                   │
                                   ▼
         GPR-VLA（唯一 checkpoint）：目标 z* − 部件信念 b → 残差 r → Action Expert → chunk
                                   │
                                   ▼
         SVL 3D 落点闭环：伺服→缓放→稳定性/谓词校验→nudge/regrasp/retry
                                   │
         BAD（条件）：站姿/高度；调试槽确认后才做一次性 dock
                                   │
         NRB：官方 human 备注剧本（先叠后撤/拉链拉开/拧回瓶盖…）→ 恢复
```

一句话：**用 VTL 把“任务帧”变成可测的 3D 量，用 O4M 把“物体现在在哪”变成持久状态，用 STG 把“计划过期”变成可触发的回滚，用 SMP/TFAC 把动作和放置锚点搬到任务帧里；所有这些都是确定性代码，唯一的学习模型仍是 GPR-VLA。**

## 0. 产物摘要

### 0.1 一句话

**在唯一的学习模型（GPR-VLA）外，加一层确定性的「时空任务帧」（STF）：用校准双目在线定位桌面/容器，用物体中心 4D 记忆跟踪位移与遮挡，用陈旧状态门控触发回滚/重规划，用任务帧动作规范化与 3D 放置锚点把“最后 3 厘米”搬到当前世界状态上。**

### 0.2 本轮四个押注

1. **VTL（Visual Task-frame Localization）**：把数据集里已有、但 API 文档没提的校准双目用起来；在线估计 `T_base_table`、`T_base_container`、物体候选，给后续所有几何一个共同坐标系。
2. **O4M + STG（Object-centric 4D Memory + Stale-state Gate）**：维护物体 ID/6D/可见性/速度/最后可见；检测“物体被移动/遮挡/步骤被撤销”，触发回看、回滚、重规划。直接对准 human/position/background/distractor 四轴。
3. **TFAC + SMP（Task-frame Action Canonicalization + Stereo Metric Placement）**：把 EE 目标与放置锚点从 base 系搬到任务帧；把上一轮的 2D 锚点升级为 3D 度量锚点。直接对准多机器人/不同桌面摆放与最后 3 厘米。
4. **BAD（Base-Aware Docking，条件性）**：把“移动底盘”重解释为“基座-桌面变换未知 + 任务化站姿”；默认不移动，只有在调试槽确认 `action.pivot` 真的执行且稳定时，才做一次性 dock。

| GR00T N1.5 [S14] | 3B 双系统 VLA（VLM + DiT） | 通用、效率 | 2D；无显式状态/记忆 |

> 上述百分比是各论文的已发表数字，不是 UniBot 榜成绩；仅用于说明方法强项/弱项。

### 2.3 共同瓶颈（按对五轴的相关性）

1. **度量 3D 精度**：2D 语义特征 + 动作专家，最后 3 厘米缺几何。
2. **持久状态**：无物体中心 track；human 轴移动/撤销后仍执行旧计划。
3. **坐标系**：动作在 base 系；多机器人/不同桌面摆放使同一像素目标对应不同 base 坐标。
4. **精细双手/可变形**：拉链、笔袋、毛巾、针筒。
5. **延迟/算力**：14B/7Hz + 远程 API 网络延迟；180s 内要留重试。

### 2.4 30% 天花板的三种解释

| 解释 | 证据 | 对 STF 的含义 |
|---|---|---|
| 语义天花板：模型不认识/不理解任务 | 未见物品轴；π0.5 的开放世界强项 | STF 只能帮几何，帮不了语义；需要 VLA/数据 |
| **状态/坐标系天花板**：目标帧错、物体移了、计划过期 | human/position 轴；步骤分差 +8.6pp；OCC4M/RoboStream/DREAM/Robust-TAMP 的记忆收益 | **STF 的主战场** |
| 接触/精度天花板：抓滑、碰撞、释放姿态 | 精细任务低成功率；终局步骤 39.8% | PILOT/SMP/SVL/NRB 的主战场 |

**判断**：三者都存在；本轮优先攻“状态/坐标系”，因为它跨轴、可解释、数据高效，且与上一轮 PILOT 互补。

### 2.5 对 STF 的启示

- 头部模型不是不聪明，而是**不知道“现在”**：当前帧不等于当前状态。
- 双目/深度是免费信号，但 API 文档没强调；这是工程红利。
- 单模型约束下，**确定性几何层**比“再加一个学习模型”更安全。
- 33k 数据上，堆参数的边际收益低于“把状态接对”。

## 3. 评分算术与跨轴杠杆

### 3.1 闸门与步骤分

```text
成功率 = P(32/32 任务的所有步骤完成)      # 终局步骤是闸门
步骤分 = Σ w_i × P(step_i 完成)          # 终局步骤合计 1275/3200 = 39.8%
```

上一轮已抓全 32 任务 `score_steps`；本轮沿用。终局步骤权重高，意味着“最后一步失败”对成功率是 0、对步骤分是扣 39.8% 的一部分——这解释了步骤分与成功率的 +8.6pp 差。

### 3.2 320 个计分 episode

```text
32 tasks × 10 runs = 320 episodes
5 axes × 2 runs each
```

### 3.3 统计功效

```text
p = 0.30, N = 320 → SE = sqrt(0.30×0.70/320) ≈ 2.56pp
two independent proportions: SE_diff ≈ sqrt(2×0.30×0.70/320) ≈ 3.62pp
80% power, α=0.05 two-sided → ≈ 2.8×SE_diff ≈ 10pp
```

**结论**：+5pp 在 320 个独立 episode 上不显著；必须：

- 配对任务/种子（同一任务、同一初始条件，A/B 两种策略）；
- 任务级 bootstrap（重采样 32 个任务，而不是 episode）；
- 把步骤分作为第二指标（更连续、方差更小）；
- 预注册主要终点，避免事后挑轴。

### 3.4 五轴 × STF

| 轴 | 次数/任务 | 扰动 | STF 组件 | 预期 |
|---|---:|---|---|---|
| 位置 | 2 | 物体初始位置变 | VTL/O4M/SMP | 强 |
| 人为干扰 | 2 | 移动/撤销/遮挡 | O4M/STG/NRB | 强 |
| 背景 | 2 | 桌布/背景变 | VTL 度量几何/overlay | 中强 |
| 干扰物 | 2 | 多物体 | O4M 相关性选择 | 中强 |
| 未见物品 | 2 | 外观变 | O4M 几何跟踪 + VLA 语义 | 中 |

### 3.5 失败分解（假设，待调试槽验证）

```text
70% 失败
├─ 1/3 状态/坐标系 → STF
├─ 1/3 精度/放置   → PILOT/SMP/SVL
└─ 1/3 抓取/接触   → NRB/数据/力控
```

STF 救回状态错的一半：`0.70×1/3×0.5≈11.7pp` 上限；现实 +3–5pp。与 PILOT 的 +5–10pp 叠加，合计 +8–12pp 潜力。

### 3.6 为什么不是“再堆一个更大的 VLA”

- UniBot 数据 33k；头部模型预训练在百万级轨迹上；在 33k 上微调 6–14B 模型，参数边际收益低、过拟合风险高。
- 远程 API + 180s 预算：14B/7Hz 的世界模型延迟不可接受。
- 单模型合规：外挂学习模型风险高；确定性几何层没有这个问题。
- 状态错误是“信息问题”，不是“容量问题”；加容量不解决“不知道物体现在在哪”。

## 4. STF-GPR 架构

### 4.1 总图

```text
语言(160 条复述) ──► SSG 评分步骤图（32 任务步骤+权重）──► 当前步骤 s_t
                                   │
  4 路 RGB + 本体 ──► VTL 视觉任务帧（双目度量定位）
                                   │  T_base_table / T_base_container / 物体候选
                                   ▼
                     O4M 物体中心 4D 记忆（ID/6D/可见性/速度/最后可见）
                                   │
                     STG 陈旧状态门控（预测 vs 观测；relocation/occlusion）
                                   │  触发回看/回滚/重规划
                                   ▼
                     SMP 3D 放置锚点（槽位→3D 位姿→投影渲染）
                     OPT 少样本释放位姿（容器系统计）
                     ICR 检索上下文（关系键+相位键+O4M 状态）
                                   │
                                   ▼
         GPR-VLA（唯一 checkpoint）：目标 z* − 部件信念 b → 残差 r → Action Expert → chunk
                                   │
                                   ▼
         SVL 3D 落点闭环：伺服→缓放→稳定性/谓词校验→nudge/regrasp/retry
                                   │
         BAD（条件）：站姿/高度；调试槽确认后才做一次性 dock
                                   │
         NRB：官方 human 备注剧本（先叠后撤/拉链拉开/拧回瓶盖…）→ 恢复
```

### 4.2 设计不变量

1. **唯一学习模型**：GPR-VLA 一个 checkpoint；其他都是确定性代码/统计。
2. **任务帧优先**：所有几何量先转到 `T_table`；base 系只用于最终接口。
3. **物体中心**：状态以物体 ID/6D/可见性表达，不用像素/视频帧表达。
4. **陈旧门控**：预测与观测不一致时，先回看/回滚，不盲目继续。
5. **度量放置**：锚点是 3D 位姿 + 不确定度，不是 2D 点。
6. **可回退**：VTL 失败回 base 系；O4M 失败回单帧；STG 失败回顺序执行；BAD 失败回零。
7. **延迟预算**：VTL+O4M+STG+SMP <30ms/控制周期；不拖垮 7–30Hz 控制。

### 4.3 数据流

- **每集开始**：`reset()` → 清空 O4M/STG → 等第一帧双目 → VTL 拟合桌面/容器 → 初始化任务帧 → SSG 选步骤。
- **每个 chunk**：取 4 路 RGB（`obs_delta_indices`：头 [-10,-5,-2,0]，腕 [-2,0]）→ VTL 更新 → O4M 关联 → STG 检查 → SMP 锚点 → GPR-VLA 出动作 chunk → TFAC 转回接口帧 → 执行。
- **终局**：SVL 3D 落点闭环 → 稳定性/谓词校验 → 成功/重试。
- **异常**：STG 触发 → 回看/回滚；NRB 触发 → 恢复剧本；BAD 触发 → 站姿/一次性 dock。

### 4.4 接口

- 控制空间：`ee` 优先（TFAC 最自然）；`joint` 作为回退（IK）。
- 动作 chunk：8–16 步（30Hz 下 0.27–0.53s）；终局附近用 8 步提高反应。
- `image_resize`：头部左右必须**同尺寸同裁剪**（否则双目标定失效）；腕部可单独 240×320。
- `obs_delta_indices`：头 [-10,-5,-2,0]，腕 [-2,0]；reset 后历史不足由评测器 pad 首帧。
- `action.pivot`：默认零/任务化 height；BAD 开启时单独输出。

## 5. 组件规格

### 5.1 VTL（Visual Task-frame Localization）

**输入**：`cam_left_high`、`cam_right_high`、腕部 RGB、`lower_body`（waist yaw/roll/pitch）、`left/right_ee_pose_gripper_base`、语言/SSG 当前步骤。

**输出**：
- `T_base_table`：桌面平面 + 朝向 + 原点（机器人正前方桌面中心）。
- `T_base_container`：容器/架子/盘子/盒子的 6D 位姿 + 尺寸。
- `objects[]`：物体候选（质心、PCA 朝向、包围盒、可见性、置信度）。
- `depth_valid`：双目有效像素比例。

**步骤**：

1. **相机外参重建**：`T_base_camera = FK_waist(lower_body) · T_waist_camera`；用 G1 URDF；若 waist 关节不可靠，用腕部手眼标定交叉验证。
2. **双目校正/匹配**：用 `camera_params.head_stereo` 的 K/R/T；SGBM/BM；左目为参考；剔除低纹理/反光/透明。
3. **桌面拟合**：RANSAC 平面；法向与机器人朝向对齐；原点取桌面前沿中心；`T_base_table`。
4. **容器 6D**：对架子/盘子/盒子做平面/线段/包围盒拟合；用任务先验（SSG/语言）选容器；`T_base_container`。
5. **物体候选**：桌面以上高度簇 + 颜色簇 + 点云簇；与上一帧 track 关联；输出质心/PCA/可见性。
6. **置信度**：平面内点率、深度有效率、重投影误差；低于阈值时输出 `valid=false`，上层回退。

**关键参数**：

```text
depth range: 0.2–1.2 m
SGBM: block 5–7, disp 64–128, uniqueness 10, speckle 100
plane RANSAC: 300 iters, 8mm inlier
table frame: z 法向, x 机器人朝向投影, 原点桌面前沿中心
container: 平面/线段/包围盒, 1–2cm/5°
object: 1cm 质心, PCA 朝向, 可见性 0–1
confidence: inlier>0.55, depth_valid>0.60, reproj<2px
```

**失败模式**：透明试管/针筒/拉链（深度无效）、反光桌面（平面漂移）、纯色背景（纹理不足）、遮挡（容器不可见）。对策：分桶、腕部 RGB 单目先验、上一帧 track 外推、回退 base 系。

**为什么是创新**：数据集/接口把双目放在那里，但 API 文档没强调；多数基线当两路 RGB。VTL 不是新传感器，是“把已有传感器接对”。

### 5.2 O4M（Object-centric 4D Memory）

**状态**（每个物体）：

```text
id, class/distribution, centroid (table frame), 6D pose, bbox size,
velocity (table frame), visibility, last_seen_t, confidence,
relations: on/in/behind/held/occluded, source (vision/gripper/human)
```

**关联**：匈牙利匹配 + 马氏距离（位置/速度/尺寸） + 外观直方图；门限按任务/物体类别分桶；新物体分配新 ID；长时间未见标 `lost`。

**事件**：

- **relocation**：物体质心位移 > `max(2cm, 3σ)` 且非机器人夹爪所致 → 触发 STG 回看/回滚。
- **occlusion**：可见性 <0.3 但上一帧可见 → 用最后速度外推 + 腕部视角补看；不立即判丢。
- **removal/undo**：物体从容器内回到桌面、或步骤谓词从真变假 → 触发 NRB/回滚。
- **human interference**：检测到人手/手臂进入工作区（肤色/深度/运动）→ 暂停 0.3–0.5s，等稳定后重定位。

**记忆窗口**：当前 episode 全历史；跨 episode 不共享（避免污染）；每个物体最多 64 个关键帧。

**输出**：`state_t`（物体 ID/6D/可见性/关系）；`events[]`（relocation/occlusion/removal/human）；`confidence`。

**为什么是创新**：VLA 的上下文是图像/本体；O4M 给它“物体现在在哪”的持久状态。OCC4M/RoboStream/SOMA/RoboMME/DREAM 都证明这类记忆能救遮挡/移动；我们把它做成无学习、CPU、可解释的版本，符合单模型约束。

### 5.3 STG（Stale-state Gate）

**两个信号**：

1. **预测 vs 观测**：O4M 预测的物体位置/步骤谓词 vs 当前 VTL/O4M 观测；残差 > 阈值 → 状态陈旧。
2. **计划相位**：SSG 当前步骤的谓词（如 `in_container`、`zipped`、`cap_on`）在观测中不成立 → 计划过期。

**动作**：

| 触发 | 动作 | 代价 |
|---|---|---|
| 轻微不一致（<2cm/短时遮挡） | 回看 1–2 帧，继续 | 低 |
| 物体 relocation / 谓词变假 | 回滚到步骤起点，重定位，重规划 | 中 |
| 人手进入/持续遮挡 | 暂停，等稳定，重定位 | 低 |
| 多次回滚失败 | 放弃当前子任务，保步骤分 | 低 |

**阈值**：位移 >2cm 或 >3σ；谓词置信 <0.6；人手检测置信 >0.7；回滚上限 1 次/子任务；总时长守卫 150s。

**为什么是创新**：Robust-TAMP 证明“何时/哪里重规划”本身是瓶颈；我们把重规划触发从“固定频率”变成“状态陈旧事件”，更省算力、更可解释。

### 5.4 TFAC（Task-frame Action Canonicalization）

**两种实现**：

1. **动作规范化**（推理 wrapper）：策略输出 base 系 EE 目标 `p_base`；转到任务帧 `p_table = T_table_base · p_base`；在任务帧做修正/伺服；再转回 base 系。无需重训。
2. **观测/标签规范化**（训练）：训练时把 EE 位姿、放置锚点、物体状态都转到任务帧；推理时同样转；策略学“任务帧动作”。需要微调。

**为什么有效**：多机器人/不同桌面摆放只改变 `T_base_table`；任务帧动作不变。这与“数据增强”不同：它改变的是**表示**，不是样本。

**风险**：任务帧估计误差会传播；用置信度门控，低置信回退 base 系；训练时注入 `T_base_table` 噪声（±5cm/±5°）做鲁棒性。

**与 AnyMug/OC-VLA/Unify Robot Actions/MoF 的区别**：它们做相机帧/物体帧/运动帧规范化；我们做**桌面任务帧 + 容器帧**，且与 SSG/PILOT 的步骤/放置锚点绑定；更适合桌面操作。

### 5.5 SMP（Stereo Metric Placement）

**上一轮 PGL**：2D 锚点（像素/归一化坐标）+ 投影 → 缺度量深度。

**本轮 SMP**：

1. **槽位检测**：容器/架子/盘子/盒子的可放置区域；用 VTL 的 3D 平面/包围盒。
2. **3D 锚点**：`p_table^*`（槽位中心/边缘/堆叠高度）+ 朝向 + 不确定度。
3. **投影渲染**：把 3D 锚点投影到当前双目/腕部图像；渲染十字/圆环/箭头 overlay。
4. **伺服**：SVL 用双目深度把 EE 伺服到 `p_table^*`；终局用腕部近距离修正。
5. **不确定性**：深度方差 + 槽位拟合残差 + 物体尺寸；高不确定时多视角/多帧平均。

**收益**：把“最后 3 厘米”从 2D 像素误差变成 3D 度量误差；对位置/背景/不同桌面高度更稳。

**风险**：透明/反光容器；槽位检测错；深度外参误差。对策：分桶、腕部单目、置信度门控。

### 5.6 BAD（Base-Aware Docking，条件性）

**默认**：`action.pivot` 输出零/任务化 height；不做底盘运动。

**可选**：

1. **站姿选择**：根据第一帧桌面高度/物体距离，选任务化 height（0.61–0.74m）和 waist pitch；一次性设置，不连续控制。
2. **一次性 dock**：若评测起始基座位姿随机，VTL 估计 `T_base_table`；计算到 canonical 桌面相对位姿的 `(dx,dy,dθ)`；若 |dx|,|dy|<0.3m、|dθ|<15°，用 `action.pivot` 一次性移动；重新 VTL；再跑固定基座策略。
3. **安全**：限速 0.05m/s、0.2rad/s；倾角/电流守卫；失败立即停；不重复尝试。

**Go/No-Go**：调试槽确认 `action.pivot` 真的执行、基座移动可重复、不触发保护；否则永久关闭。**BAD 不是主线**，只是“移动底盘”这个词的正确落点。

### 5.8 CGC（Compliance Geometry Layer）

**目的**：在单模型硬约束下，证明 STF 不引入第二个学习模型。

**清单**：

- VTL：SGBM/RANSAC/DBSCAN/PCA，经典算法。
- O4M：匈牙利/Kalman/规则，经典算法。
- STG：阈值/谓词，规则。
- SMP：几何投影/渲染，经典。
- TFAC：坐标变换，无参数。
- 若用预训练分割/深度/光流：必须书面允许/蒸馏/替换；默认不用。

## 6. 伪代码

### 6.1 主循环

```python
def act(obs, ctx):
    # 0) reset / 首帧
    if ctx.first:
        ctx.T_table = VTL.fit_table(obs)          # 可能失败
        ctx.containers = VTL.fit_containers(obs)
        ctx.memory = O4M.init(obs, ctx.T_table)
        ctx.step = SSG.current_step(obs.language, ctx.memory)
        ctx.first = False

    # 1) 视觉任务帧
    vtl = VTL.update(obs, ctx.T_table, ctx.containers)
    if not vtl.valid:
        return fallback_base_policy(obs)

    # 2) 物体 4D 记忆
    mem = O4M.update(ctx.memory, vtl, obs, ctx.T_table)

    # 3) 陈旧状态门控
    stale = STG.check(mem, ctx.step, obs)
    if stale.rollback:
        ctx.step = SSG.rollback(ctx.step)
        ctx.memory = O4M.reinit(vtl)
    if stale.reobserve:
        return hold_and_reobserve(obs)

    # 4) 3D 放置锚点 + 任务帧动作
    anchor = SMP.anchor(ctx.step, mem, ctx.containers)
    overlay = render_overlay(vtl, anchor, mem)
    action = GPR_VLA(obs, overlay, ctx.step, anchor)
    action = TFAC.to_task_frame(action, ctx.T_table)
    action = TFAC.to_api_frame(action, ctx.T_table)

    # 5) 终局闭环
    if SSG.is_terminal(ctx.step):
        action = SVL.servo(action, anchor, obs)
    return action
```

### 6.2 VTL

```python
def fit_table(obs):
    left, right = obs.cam_left_high, obs.cam_right_high
    disp = SGBM(left, right, K_left, K_right, R, T)   # rectified
    pts = reproject(disp, K_left)
    plane = RANSAC_plane(pts, 8mm, 300)
    if plane.inlier_ratio < 0.55:
        return None
    T = table_frame(plane, robot_forward(obs.lower_body))
    return T
```

### 6.3 O4M

```python
def update(memory, vtl, obs, T):
    dets = vtl.objects
    matches = hungarian(memory.tracks, dets, cost=pos+vel+size+appearance)
    for m in matches:
        m.track.update(dets[m.det], T)
    for d in unmatched(dets):
        memory.add(new_track(d, T))
    for t in unmatched(memory.tracks):
        t.visibility *= 0.5
        if t.visibility < 0.3:
            t.lost = True
    return memory
```

### 6.4 STG

```python
def check(memory, step, obs):
    pred = memory.predict(step.object_id)
    obs_pos = memory.observed(step.object_id)
    if obs_pos is None:
        return Gate(reobserve=True)
    if norm(pred.pos - obs_pos.pos) > max(0.02, 3*pred.sigma):
        return Gate(rollback=True)
    if not step.predicate(obs, memory):
        return Gate(rollback=True)
    if human_detected(obs) > 0.7:
        return Gate(pause=True)
    return Gate()
```

### 6.5 TFAC

```python
def to_task_frame(action, T_table_base):
    p_table = T_table_base @ action.ee_target
    return action.replace(ee_target=p_table)

def to_api_frame(action, T_table_base):
    p_base = inv(T_table_base) @ action.ee_target
    return action.replace(ee_target=p_base)
```

```python
def anchor(step, memory, containers):
    slot = detect_slot(containers[step.container_id], step.object)
    p = slot.center + slot.normal * (step.object.height/2 + 0.005)
    sigma = slot.sigma + memory.sigma(step.object_id)
    return Anchor(p=p, yaw=slot.yaw, sigma=sigma)
```

## 7. 数据引擎

### 7.1 任务帧标签

- 对 32 任务逐集运行 VTL（离线），得到 `T_base_table`、`T_base_container`、物体轨迹。
- 人工抽检 5%/任务；标定误差 >2cm 的集剔除或重标。
- 输出：`table_frame.parquet`（episode_id, T, confidence, source）。
- 用途：TFAC 训练标签、SMP 3D 锚点、O4M 初始化。

### 7.2 物体轨迹

- 用 VTL 物体候选 + 关联，生成每集物体轨迹；人工抽检 2%/任务。
- 对透明/反光物体，用腕部 RGB + 单目先验，标 `depth_invalid`。
- 输出：`object_tracks.parquet`（episode_id, frame, object_id, pose, visibility, confidence）。

### 7.3 relocation/occlusion 事件

- 从轨迹自动挖掘：位移 >2cm/3σ、可见性跌落、谓词变假。
- 对齐官方 human 备注（human_1_note/human_4_note）验证。
- 输出：`events.parquet`（episode_id, t, type, object_id, magnitude）。
- 用途：STG 阈值、NRB 剧本、调试槽采样。

### 7.4 overlay 生成

- 输入：VTL/SMP/O4M 输出；输出：头部/腕部图像上的 3D 框、桌面网格、槽位圆环、箭头、文字。
- 训练时与推理时同一渲染器；随机扰动（颜色/线宽/透明度/延迟 0–2 帧）做鲁棒。
- 不遮挡关键接触区域；不写会泄漏答案的文本（如“把杯子放这里”可以，写“第 3 步”不行）。

### 7.5 human 备注

- 32 任务中至少 15 个有 `human_*_note`；解析成“扰动剧本”（先叠后撤/拉链拉开/拧回瓶盖/抓电池动绿盒）。
- 用作 NRB 恢复模板 + 调试槽采样；不假设它是唯一评测条件。
- 对应 5 类×2 中的 human 2 次；每任务至少准备一个恢复分支。

### 7.6 数据预算

```text
33,276 episodes × 30fps × 5.5s ≈ 5.5M frames? 实际 18.28M frames (含多相机/长度差异)
训练子集：每任务 300–500 episodes（共 10k–16k）
验证：每任务 50 episodes（1.6k）
O4M/VTL 离线：32 任务全量，CPU 集群 1–2 天
overlay 渲染：训练子集，GPU/CPU 2–3 天
```

## 9. 接口工程

### 9.1 控制空间

- **ee**：TFAC/SVL 最自然；动作 6D（xyz+rpy）+ 夹爪；`action.pivot` 共享。
- **joint**：回退；需要 IK；TFAC 仍在任务帧算，再 IK 到关节。
- 选择：默认 `ee`；若官方 `ee` 有抖动/限位问题，切 `joint`。

### 9.2 观测堆叠

- `obs_delta_indices`：头 [-10,-5,-2,0]，腕 [-2,0]；`obs_delta_indices` 只对图像，不对本体。
- `image_resize`：头左右同尺寸同裁剪；腕可单独。
- 历史不足：评测器 pad 首帧；策略侧检测并降级。

### 9.3 reset

- 清空 O4M/STG/ICR；等第一帧双目；VTL 拟合；若失败，等 1–2 帧重试；仍失败 → base 系回退。
- 不跨 episode 共享物体 ID/状态；防止污染。

### 9.4 延迟

```text
VTL: 10–30ms (SGBM 480×640 + RANSAC)
O4M: <5ms
STG: <1ms
SMP: <5ms
overlay: 5–15ms
GPR-VLA: 50–150ms (6B, chunk)
总: ~100–200ms/chunk；30Hz 下 3–6 帧
```

- 远程 API 网络延迟另计；用 chunk 掩盖；终局用短 chunk。

### 9.5 多端口

- 每个 episode 独立进程/状态；不共享 O4M/STG。
- FLEET 检查单：端口、token、日志、超时、重连、清理。
- 不在多实例间共享缓存/模型状态（除非只读）。

### 9.6 失败处理

- VTL 失败 → base 系策略；O4M 失败 → 单帧；STG 失败 → 顺序执行；BAD 失败 → 零。
- 任何异常：保步骤分，不冒险；180s 守卫。
- 日志：每 chunk 记录 VTL/O4M/STG/SMP 置信度、动作、耗时；便于复盘。

### 10.3 扰动

- 基座：3 个距离（0.6/0.75/0.9m）×3 个角度（-15°/0/+15°）；TFAC vs base 系。
- 桌面高度：0.61/0.68/0.74m；BAD 站姿。
- 物体位移：2/5/10cm；O4M/STG。
- 遮挡：人手/盒子；O4M。
- 背景：桌布/纯色；VTL。
- 未见物体：替换外观；VLA 语义（STF 只保证几何）。

### 10.4 计分

- 2 次计分运行（避免单次噪声）；配对任务/种子。
- 主要终点：总平均成功率；次要：步骤分、五轴分轴。
- 任务级 bootstrap 95% CI；不把 +1–2pp 当结论。

### 11.2 新增/升级点的六要素

#### I14 · VTL（视觉任务帧定位）——主押注

- **动机**：API 不给相机外参；数据集有校准双目但多数基线当两路 RGB；桌面任务的一切几何都需要一个共同帧。
- **差异**：不是房间 SLAM，不是新传感器；是桌面尺度三级定位（桌面/容器/物体），用已有标定 + 经典几何，单模型合规。
- **可行性**：SGBM/RANSAC/PCA 成熟；58mm 基线、0.3–0.8m 工作距离可达毫米–厘米；CPU 10–30ms。
- **资源**：1 名几何/视觉工程师；CPU 集群；无需训练；1–2 周。
- **步骤**：外参重建 → 桌面拟合 → 容器 6D → 物体候选 → 置信度 → 离线抽检 → overlay。
- **风险**：透明/反光/纯色/遮挡；外参误差；平面漂移。对策：分桶、腕部单目、置信度门控、base 系回退。

#### I15 · O4M（物体中心 4D 记忆）——主押注

- **动机**：VLA 不知道物体现在在哪；human/position 轴移动/遮挡后仍执行旧计划。
- **差异**：不做 14B 视频世界模型；做物体级状态（ID/6D/可见性/速度/关系），CPU、可解释、单模型合规；比帧堆叠更持久。
- **可行性**：匈牙利/Kalman/规则成熟；OCC4M/RoboStream/SOMA/RoboMME/DREAM 已证明记忆收益；数据有 32 任务轨迹可挖。
- **资源**：1 名工程师；CPU；2–3 周（含事件挖掘）。
- **步骤**：轨迹生成 → 关联 → 事件（relocation/occlusion/human）→ STG 阈值 → 调试槽。
- **风险**：关联错/ID 切换；透明物体；人手误检；记忆污染。对策：马氏距离 + 外观 + 关系；分桶；episode 隔离。

#### I16 · TFAC（任务帧动作规范化）——实验押注

- **动机**：动作在 base 系表达；多机器人/不同桌面摆放使同一像素目标对应不同 base 坐标。
- **差异**：不是数据增强；改变动作表示；与 AnyMug/OC-VLA/Unify/MoF 的相机/物体/运动帧不同，我们做桌面/容器任务帧，并与 SSG/PILOT 绑定。
- **可行性**：坐标变换简单；可用推理 wrapper 先验证（无需重训）；再用标签微调。
- **资源**：1 名工程师 + LoRA 微调；2–3 周。
- **步骤**：T_table 标签 → 训练时转到任务帧 → 注入 T 噪声 → 跨基座测试 → 对比 base 系。
- **风险**：T 估计误差传播；策略不适应任务帧；与 `action.pivot` 耦合。对策：置信度门控、回退、噪声训练。

#### I17 · BAD（基座/站姿）——条件押注

- **动机**：“移动底盘”是隐藏自由度；演示基座不动，但评测可能不同起始位姿/桌面高度。
- **差异**：不学 locomotion；只做任务化站姿 + 一次性 dock；默认零输出；安全限幅。
- **可行性**：`action.pivot` 存在；但演示几乎为零，执行器是否响应未知；需要调试槽验证。
- **资源**：0.5 人；1 周；主要是真机安全测试。
- **步骤**：调试槽读 pivot 执行 → 小角度/小位移 → 视觉伺服 dock → 失败即关。
- **风险**：pivot 不执行/不稳定/触发保护；基座移动改变相机外参；时间超支。对策：默认关；限幅；重新 VTL；总时长守卫。

#### I18 · CGC（合规几何层）——合规押注

- **动机**：官方“不得混合多个模型”；外部学习模型（SAM2/FoundationPose/RAFT-Stereo）有合规风险。
- **差异**：把 STF 做成“确定性几何 + 唯一 checkpoint”；不是公关话术，是架构约束。
- **可行性**：经典算法足够；若不够，蒸馏/替换；可请官方书面确认。
- **资源**：0.5 人；持续。
- **步骤**：依赖清单 → 合规矩阵 → 模型卡 → 提交说明 → 必要时邮件确认。
- **风险**：官方认定 overlay/辅助头是第二个模型；对策：默认不引入外部模型；披露；可关闭。

#### I1 升级 · STG（原 SSG）

- **动机**：SSG 只匹配语言/步骤；不检查物体状态；计划过期仍执行。
- **差异**：加 O4M 预测 vs 观测、谓词真值、人手检测；触发回看/回滚/重规划。
- **可行性**：规则 + 阈值；Robust-TAMP 证明“何时重规划”是瓶颈；CPU <1ms。
- **资源**：0.5 人；1–2 周。
- **步骤**：谓词库 → 阈值 → 回滚策略 → 调试槽。
- **风险**：误触发/耗时；对策：双阈值、限 1 次回滚、总时长守卫。

#### I2 升级 · SMP（原 PGL）

- **动机**：2D 锚点缺深度；最后 3 厘米靠像素不够。
- **差异**：3D 槽位/锚点 + 双目深度 + 不确定度；与 VTL/O4M 绑定。
- **可行性**：双目 + 平面/包围盒；SVL 已有闭环。
- **资源**：1 人；2 周。
- **步骤**：槽位检测 → 3D 锚点 → 投影 → 伺服 → 对比 2D。
- **风险**：透明/反光容器；对策：分桶、腕部、置信度。

## 12. 风险、合规与开关

### 12.1 技术风险

| 风险 | 概率 | 影响 | 缓解 | 停止条件 |
|---|---|---|---|---|
| 双目透明/反光失效 | 高 | 中 | 分桶；腕部单目；base 系回退 | 深度有效率 <60% → 退出该任务 |
| 外参重建误差 | 中 | 高 | waist FK + 手眼交叉验证 + 在线桌面自标定 | 桌面帧 >1cm/2° → 回退 |
| O4M ID 切换 | 中 | 中 | 马氏+外观+关系；短时 memory | MOTA <0.7 → 简化 |
| STG 误触发 | 中 | 中 | 双阈值；限 1 次；总时长守卫 | 触发 >3 次/任务 → 关 |
| TFAC 传播误差 | 中 | 高 | 置信度门控；噪声训练；回退 | 跨基座无增益 → 关 |
| BAD 不稳定 | 高 | 低 | 默认零；调试槽验证；限幅 | 任一异常 → 永久关 |
| overlay 被忽略 | 中 | 中 | 同分布训练；A/B | 跟随误差不降 → 关 |
| 统计噪声 | 高 | 中 | 配对/任务级 bootstrap；步骤分 | CI 跨 0 → 不上线 |

### 12.2 合规

- **唯一学习模型**：GPR-VLA 一个 checkpoint；VTL/O4M/STG/SMP 确定性。
- **外部依赖**：默认不用学习模型；若用，书面允许/蒸馏/替换；模型卡披露。
- **数据**：仅用官方数据 + 自采实验室数据（L2L）；不碰测试输入；不硬编码任务答案。
- **安全**：力/速度/时长限幅；BAD 默认关；异常保步骤分。
- **透明度**：提交说明写清架构、依赖、许可证、失败模式。

### 12.3 Go/No-Go

| 关卡 | 通过 | 失败 |
|---|---|---|
| VTL 离线 | 桌面帧 <1cm/2°，深度有效 >60% | 回退 base 系；只做 SMP 的 2.5D |
| O4M/STG 离线 | relocation 延迟 <0.5s，MOTA >0.8 | 简化；只做单帧 |
| 调试槽 T27 | 终局 +10pp 或步骤分 +5pp | 回炉；不上计分 |
| TFAC 跨基座 | +5pp vs base 系 | 关 TFAC |
| BAD | pivot 执行稳定 | 永久关 |
| 计分运行 | 2 次，配对 CI 跨 0 则停 | 只保留离线/调试槽 |

### 12.4 Kill switches

```text
STF_ENABLE=0        # 回 base 系策略
VTL_ENABLE=0        # 关双目，单目/腕部
O4M_ENABLE=0        # 关记忆，单帧
STG_ENABLE=0        # 关回滚，顺序执行
TFAC_ENABLE=0       # 关任务帧，base 系动作
BAD_ENABLE=0        # 关底盘/站姿
OVERLAY_ENABLE=0    # 关 overlay
```

默认全开（除 BAD）；任一异常可热关；日志保留。

## 15. 开放问题

1. **`cam_left_high/cam_right_high` 是否就是 `head_stereo_left/right`？** 命名/分辨率/基线推断是，但需第一帧调试确认；若不是，VTL 需重新标定。
2. **评测时相机外参是否与数据集一致？** 不同机器人/头部俯仰可能不同；在线自标定是否足够？
3. **`action.pivot` 在评测中是否真的执行？** 演示近零；需调试槽读回 base 位姿/IMU。
4. **human 轴的两次运行是否严格按 `human_1_note/human_4_note`？** 编号含义未官方解释；按“高价值剧本”准备，不假设唯一。
5. **单模型合规的边界**：确定性 overlay/辅助头/经典 stereo 是否算“混合模型”？需官方书面确认；默认最保守。
6. **步骤分是否按 10 次运行平均？** 规则说“总平均步骤分”；按任务平均再总平均，需确认权重。
7. **未见物品轴的“未见”程度**：外观替换/类别替换/功能替换？STF 只保证几何，语义仍靠 VLA。
8. **调试槽的成功判据是否与计分槽一致？** 需确认，否则调试槽结论不能外推。
9. **网络延迟/API 限流**：远程 API 的 p95 延迟？chunk 大小如何适配？
10. **排行榜占位何时替换为真实数据？** 替换后头部方法/成功率可能变；机制设计不依赖占位数字。

## 16. 一句话押注

**本轮最值得押注的是 STF（时空任务帧）层：用校准双目在线定位桌面/容器、用物体中心 4D 记忆跟踪位移与遮挡、用陈旧状态门控触发重规划，把“放置”从一次性 2D 锚点升级为“当前 3D 世界状态”上的闭环——这比再堆一个更大的 VLA 更可能在 UniBot 五轴泛化上把成功率推过 30%。**
