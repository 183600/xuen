# 第 1 轮（新循环）· RANK-CTX：把排行榜当噪声传感器，把上下文做成物体图，把四足机器人的“先看再走”搬进 G1 桌面操作

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新灵感循环第 1 轮，三个词是「**排行榜**」「**上下文理解**」「**四足机器人**」。本轮承接第 12 轮 CHUNK-SERVO 的执行层，但不重复它：CHUNK-SERVO 回答“怎么在 5 步内修正最后 3 厘米”，本轮回答“**修正什么、什么时候该停、该看、该重试，以及凭什么相信这次修改真的涨点**”。

## 0. 先给结论：三个事实，一个押注

### 0.1 三个会改变方案的事实

1. **排行榜是“预览/合成快照”，不是可复现的 live SOTA。** 2026-10-31 官网榜单显示 8 行分数（MolmoAct2 29.7% 到 GR00T N1.5 20.5%），但 `leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`；8 个模型 ×32 任务的 `step_score` 对 `success_rate` 回归 `R² > 0.999999`、最大残差 `<0.006`；任务级成功率出现 27.29%、27.85%、38.43% 等不可能是 10 次试验产生的数值；详情页 32 个视频全部是“测试视频占位”。结论不是“榜单数字一定假”，而是：**它不能被当作 SOTA、任务难度表或失败分布；只能当作模型家族/难度量级的弱先验。**
2. **10 次/任务的评测，使任务级排名高度噪声；320 次试验只能把全局标准误压到约 2.4pp。** 单任务在 `p=0.5` 时标准误约 15.8pp，95% 置信区间约 ±31pp；在 `p=0.3` 时约 ±28pp。320 trials、`p=0.25` 时全局标准误约 2.42pp，95% 区间约 ±4.7pp。**一次全量提交分辨不出 2–3pp 的改进**；必须在单任务通道做配对 A/B，而不是看榜单名次抖动。
3. **33k 条演示全是成功数据，缺的正是“失败之后怎么办”的上下文。** 32 个 HF 数据集合计 33,276 episodes / 18,282,246 frames / 169.28h @30fps；没有失败标签、没有恢复动作、没有人为干扰轨迹。模型可以从演示里学会“正常流程”，但学不会“物体被挪走、夹爪夹空、目标被遮挡、做到一半被人打断”之后的状态推断与重规划。**上下文层是结构性缺口，不是模型参数不够。**

### 0.2 本轮的押注：RANK-CTX

> **把 33k 成功演示离线编译成「相位 × 物体 × 异常」上下文图；在线用确定性的立体几何、腕部内参、EE/夹爪本体信号维护它；把上下文压缩成 VLA 可读的 context card；当上下文不确定、物体被移动/遮挡或夹爪滑移时，用四足式的小幅度主动重观测（BODY-LOOK）和本体反射恢复；用私有配对评测（RANK-CAL）而不是预览榜单决定是否提交。**

一句话：**不要往 VLA 里塞更多历史，先把“现在处于哪个阶段、物体在哪、什么变了”变成可观测、可验证的状态。**

|---|---|---|---|

## 1. 三个词，三条可证伪的假设

| 假设 | 内容 | 最小检验 | 通过标准 | 失败就剪枝 |
|---|---|---|---|---|
| **H1 排行榜** | 私有配对评测能在 10–20 对单任务 trials 内检出 ≥5pp 的真实提升 | 同一任务、同一初始条件，baseline 与 intervention 交替跑；bootstrap 配对区间 | 差值 95% 区间下界 >0，且 ≥5pp | 若区间跨 0，停止该改动，不提交 |
| **H2 上下文** | CTX-GRAPH + CTX-CARD 在人为干扰/遮挡/位置泛化上带来 ≥10pp | 选 3 类任务（动态/长程/插入），每类 2 个任务，单任务通道 | 3 类中至少 2 类 ≥10pp，且无任务掉 >5pp | 若只在 1 类有效，缩成该类的专用模块 |
| **H3 四足** | BODY-LOOK + 滑移反射能把“被打断/夹空/滑落”的恢复成功率提高 ≥15pp，且不增加 >5% 时长 | 注入遮挡、移动物体、夹空三类扰动；记录恢复时间/碰撞 | 恢复率 ≥15pp，碰撞/超时率不升 | 若安全违规或收益 <5pp，退回“只停/只重规划” |

这三条不是“三个宏大名目”，而是三个可以在一周内被证伪的实验。**本轮只押 H1+H2 的组合；H3 是差异化来源，但必须先过安全门。**

### 2.2 规则与 API：上下文层必须实时、轻量、可隔离

官方参赛手册与提交 README（2026-10-31 复核）给出：

- 仅设通才单模型赛道；所有任务须基于**同一模型**，不得混合多个模型；模型类型不限。
- 32 任务 ×10 次；5 类泛化各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰；单次真机上限 **180s**。
- 排名先看 32 任务总平均成功率，再看总平均步骤分，再相同看更早提交。
- 跨 **N 台机器人**；从 **8765** 起暴露 N 个连续端口；每端口独立 episode，`reset()` 状态必须隔离。
- 另有**不计分的单任务测试通道**，是做配对 A/B 的唯一合规通道。

API 关键约束：

| 项 | 事实 | 对上下文层的约束 |
|---|---|---|
| 观测 | 四路 RGB 480×640：头双目 + 双腕 | 头双目可做米制深度；腕部近距看接触 |
| 本体 | 双臂关节 `[7]`、EE 位姿 `[6]`、夹爪 `[1]`、`lower_body [15]` | 可用本体历史做滑移/接触代理 |
| 动作 | `joint` 或 `ee` 互斥；`ee` 为 base 系绝对位姿 | 视觉伺服输出绝对目标；WLA 相对动作要 compose |
| 共享动作 | `action.pivot [7]` 必须返回 | BODY-LOOK 只能用 `pivot` 的小幅动作，语义待标定 |
| chunk | `action_chunk_size int ≥1`，提交内固定；官方示例是 **8**，不是 30 | 30 只是 WLA 默认 horizon；挑战赛可显式选 5/8 |
| 缺失 | 无 depth、camera_info、force/torque、tactile | 不能做力矩接触检测；只能用几何 + 本体残差 |
| 监控 | evaluator 记录延迟、抖动、动作统计 | 上下文层必须 CPU 轻量，不能拖慢主循环 |

**重要更正**：第 12 轮写“`action_chunk_size` 固定 30”不准确。README 明确它是 `int ≥1`，由选手在 handshake 声明、整个提交内固定；`example_policy.py` 用 8。**T_a 是提交级控制参数，不是模型默认值。**

关键细节：

### 2.4 官方基线：WLA 6B + 24GB 微调，已经替我们做完“大模型”

- UnifoLM-WLA-1.0：**6B** 参数，约 **2,500h** 真机数据，**64** 个任务，支持二指夹爪与五指手。
- 默认 `chunk_size=30`、`target_fps=30`、4 步扩散去噪；动作统一 **54 维**：左右 EE 相对 xyz+rotvec、夹爪、灵巧手、腰、躯干、base、腿。
- 微调冻结 VLM，只训 DiT action head + robot-state projector，默认**单张 24GB GPU**；也支持 LoRA。
- 挑战赛 `ee` 动作是 2×6 EE + 2×1 gripper + 7 pivot = **21 维**；WLA 的 54 维必须 adapter：相对 EE compose 到绝对位姿，gripper 直通，pivot 从 base/waist/height 组合。
- **战略结论**：不从零训 6B/14B；用 WLA Base 做 action-head 微调，把新增算力投到上下文层和执行层。

## 3. 诊断：上下文到底缺在哪

### 3.1 观测是“现在”，任务是“过程”

VLA 每步看到四路 RGB + 本体 + 一句固定语言；它没有显式的“刚才发生了什么、物体还在不在、现在处于第几阶段”。33k 条演示是成功轨迹，模型可以模仿“下一步动作”，但没有被训练去回答：

- 这个物体刚才被我碰倒了，现在应该先扶正还是继续？
- 夹爪闭合了但宽度不对，是夹空了还是夹到边缘？
- 目标被人的手挡住了，应该等、绕、还是重新看？
- 我已经把杯口对准了，但杯子被人转了 15°，要不要重算？

这些不是“更大的 VLA”能自动解决的；它们需要一个**可观测的状态**。

### 3.2 成功数据不教恢复

演示里没有失败、没有重试、没有“被抓空后怎么办”。行为克隆会把成功轨迹压进权重，但不会生成失败恢复策略。人为干扰轴占每个任务 10 次中的 2 次（20% 的 trials）；如果上下文恢复能把 human 轴成功率提高 20pp，全局平均直接 +4pp——这比榜单头尾 9.2pp 的一半还多。**上下文不是锦上添花，是 20% 分数的直接杠杆。**

### 3.3 开环 chunk 不是唯一问题，甚至不是最大的问题

CHUNK-SERVO 把 30 步切成 5 步，解决“chunk 内看不到反馈”。但如果不知道“现在该对准哪个物体/受器、什么时候该停、什么时候该重试”，5 步伺服只是更快地执行一个错误目标。**执行层需要上下文层告诉它：目标是什么、置信度多少、是否该暂停重观测。**

### 3.4 榜单噪声让“涨点”不可信

单任务 10 次试验的 95% 区间约 ±28–31pp；320 次全局 95% 区间约 ±4.7pp。**一次全量提交的排名变化，很可能只是噪声。** 如果没有私有配对评测，团队会追着榜单抖动改模型，把工程预算烧在随机波动上。RANK-CAL 不是“评测工作”，它是竞赛策略的一部分。

## 4. 方法：RANK-CTX

### 4.1 总架构

```text
                    ┌──────────────────────────────────────────┐
                    │ Evaluator: N ports 8765..8765+N-1          │
                    │ 4 RGB, EE/gripper/lower_body, language     │
                    └───────────────┬──────────────────────────┘
                                    │ obs / action chunk
                                    ▼
          ┌────────────────────────────────────────────────────┐
          │ Per-port Context Service (CPU, deterministic)       │
          │  ├─ CTX-GRAPH: object slots + phase + anomaly       │
          │  ├─ CTX-CARD: compress to ≤128 tokens               │
          │  ├─ BODY-LOOK: active re-observation (pivot/waist)  │
          │  ├─ CTX-SERVO: 5-step visual servo gating           │
          │  ├─ PROPRIO-REFLEX: grip/slip/contact proxy         │
          │  └─ fallback: hold / VLA replan / safe retreat      │
          └───────────────┬────────────────────────────────────┘
                          │ async, batched context + images
                          ▼
          ┌────────────────────────────────────────────────────┐
          │ Shared VLA server (GPU)                             │
          │ UnifoLM-WLA-1.0 + optional context adapter          │
          │ (same model; no second policy)                      │
          └────────────────────────────────────────────────────┘
```

- **唯一学习模型**：VLA（WLA 微调 action head；可选 context adapter 属于同一模型）。
- **确定性层**：CTX-GRAPH、CTX-CARD、BODY-LOOK、CTX-SERVO、PROPRIO-REFLEX；无学习权重或只有同一模型内的小 adapter。
- **数据资产**：33k 成功演示 → 相位/物体/受器模板库；不是第二个策略。
- **评测层**：RANK-CAL 决定“这个改动是否值得提交”，不参与在线控制。

### 4.2 CTX-GRAPH：物体槽 + 相位 + 异常 + 不确定性

定义第 `t` 步的上下文状态：

```text
C_t = (O_t, P_t, H_t, A_t, U_t)

O_t = { o_i }: 物体/受器槽
  o_i = (id, class, T_base_obj, v_obj, visibility, grasp_width, last_seen, confidence)
P_t: 相位分布/阶段进度（reach, grasp, lift, transport, align, insert/fasten, release, retreat）
H_t: 最近 K 步动作、夹爪开合、EE 速度、失败/重试计数
A_t: 异常标志（object_moved, occluded, slip, unexpected_contact, human_interference）
U_t: 不确定性（物体位姿协方差、相位熵、异常分数）
```

更新方式：

- **几何**：头双目三角化 + 已知 `state_d435` 外参；腕部内参 + 手眼外参（一次性标定）做近距 3D；无 depth 也能得到米制点。
- **语义**：用演示模板 + 颜色/边缘/形状 + VLA 的 cross-attention 作为物体候选；**不引入第二个学习检测器**。若分割失败，`visibility` 降级，触发 BODY-LOOK 或 VLA fallback。
- **运动**：2D/3D Kalman 或常速度模型预测物体位置；`object_moved` 由新息是否超过阈值判定。
- **相位**：从演示中用夹爪闭合、EE 速度、物体-EE 相对运动、接触前减速等信号无监督分段，得到 8 个原语；在线用带 guard 的状态机/HSMM，不用学习策略。
- **异常**：滑移 = 夹爪闭合后物体相对 EE 位移/EE 跟踪残差；夹空 = 闭合宽度与演示先验不符；遮挡 = 可见像素/置信度骤降；人为干扰 = 物体速度突变 + 画面中新进入的手臂/手。

### 4.3 CTX-CARD：把图压缩成 VLA 能读的上下文

```text
[TASK] Hang the cup on the marked spot.
[PHASE] align (3/8), progress 0.62
[OBJECTS] cup @ (0.42, 0.03, 0.12) vis=0.81; rack_hook @ (0.45, 0.10, 0.18) vis=0.93
[LAST] grasp=ok; lift=12cm; slip=0.02; retries=0
[ANOMALY] none
[GOAL] hook opening at pixel (312,204); approach -z; gripper width 6.2cm
```

两种合规模式：

- **C0（零训练，先做）**：把 card 作为结构化文本追加到 `language`；不改模型、不增权重。适合第一周验证“上下文是否被 VLA 使用”。
- **C1（同一模型内 adapter）**：把 card 编码成 8–32 个 context token，通过一个小 cross-attention 注入 DiT action head；与 action head 一起微调，仍是同一个模型。参数量控制在 <10M，24GB 可跑。
- **C2（stretch）**：把演示检索到的目标裁剪图作为额外视觉 token；需要额外 projector，风险高，只在 C0/C1 都过门后做。

### 4.4 BODY-LOOK：四足式“先看再走”

四足机器人教会我们的不是“用四条腿”，而是四条原则：

1. **本体可以当接触传感器**：没有力/触觉时，用本体残差估计接触/滑移。
2. **历史可以在视觉退化时兜底**：盲走靠 proprioceptive history。
3. **身体可以主动改变视角**：不确定时挪一步/转头看，而不是硬执行。
4. **扰动后先恢复稳定，再继续任务**：反射优先于原计划。

对应到 G1 桌面：

- **候选动作** `u ∈ U_body`：小幅 waist yaw/pitch、`pivot` height/angle、必要时很小的 base 旋转；**不走路、不跑跳、不离开桌面工作区**。
- **信息增益**：`IG(u) = H(o_t | z_{1:t}) - E[H(o_{t+1} | z_{1:t}, u)]`；选 `argmax IG(u) - λ R(u)`，其中 `R(u)` 是碰撞/工作空间/时长风险。
- **触发条件**：`U_t` 高、`visibility` 低、`object_moved` 为真、连续两次夹空/滑移、或人为干扰后目标丢失。
- **安全包络**：只在双臂处于安全位、无接触、物体不在手中时执行；限制角速度/高度/时长；超时回中性位；任何碰撞风险立即回退 VLA/hold。
- **P0 标定**：`action.pivot` 的 7 维语义未知；先在单任务通道用静态测试标定哪些维度改变视角、哪些会移动 base；标定前只使用中性值，BODY-LOOK 默认关闭。

### 4.5 CTX-SERVO：执行层继承 CHUNK-SERVO，但由上下文门控

- VLA 仍可输出 30 步计划；提交的 `action_chunk_size` 选 5 或 8（不是 30），在 chunk 内做一次视觉伺服。
- 目标不是绝对图像，而是 `T_base_ee^d = T_base_F · T_F_ee^d`：`F` 是物体/受器坐标系（杯架钩、网口、拉链滑块、锁孔、瓶盖、碗沿）。
- 门控：
  - 相位 = 接触密集 & `U_t` 低 → 5 步伺服；
  - 相位 = 运输/接近 & `U_t` 低 → 直接执行 VLA chunk；
  - `U_t` 高 / 异常 → 停、BODY-LOOK、重定位、重规划；不在错误目标上伺服。
- 滑移/夹空反射：夹爪闭合后若 `slip_score` 超阈值，先减速/停，再决定“重新抓”还是“继续但降低速度”；不引入第二个学习策略。

### 4.6 RANK-CAL：把排行榜当噪声传感器

**离线/单任务通道：**

- 每个任务 `t` 的 10 次试验是 5 类泛化各 2 次；配对 A/B 必须固定任务和初始条件，交替 baseline/intervention。
- 用分层贝叶斯：`y_{t,j} ~ Bernoulli(p_t)`，`logit(p_t) = μ + a_t + b`；`a_t` 是任务难度，`b` 是方法效应；先验弱信息，避免 10 次试验的极端估计。
- 报告**配对差值**和 bootstrap 95% 区间，不报告两个独立平均值。
- 用序贯 halving：先给每个候选任务 4–6 对，淘汰明显无效的，把预算留给 `P(Δ>0)` 高且 `Δ` 大的任务。

**全量提交：**

- 用 Monte Carlo 模拟 `P(rank ≤ k)`：对手分数用宽先验（不是预览榜单的精确值），检查结论对先验是否稳健。
- 先提交安全基线锁 tie-break；之后一次只改一个模块；每个改动必须有单任务配对证据；没有证据不提交。
- 不把“榜单名次上升”当成功；只把“配对区间下界 >0”当成功。

### 4.7 单模型合规

| 模式 | 内容 | 合规性 | 风险 |
|---|---|---|---|
| **C0** | 只把 context card 拼进 language；不改权重 | 最安全 | VLA 可能忽略文本 |
| **C1** | 同一 WLA 内加 <10M context adapter，联合微调 action head | 仍是同一模型 | 需证明不是第二策略 |
| **C2** | 确定性 CTX-GRAPH/BODY-LOOK/CTX-SERVO | 不是学习模型，是控制器 | 需在 README 说明 |
| **禁止** | 每任务一个模型、模型集成、第二个 VLM/策略、评测时在线学习 | 违规 | 不碰 |

## 5. 为什么不是 MemoryVLA / RoboTTT / D²-VLA / Harness / GloVLA

| 工作 | 它解决什么 | 它没解决什么 | RANK-CTX 的差异 |
|---|---|---|---|
| MemoryVLA | 端到端学习感知-认知记忆 | 需要训练记忆 bank；没有主动重观测；没有竞赛评测 | 运行时物体图 + context card；可零训练先验证；加 BODY-LOOK |
| RoboTTT | 8K 上下文 + TTT | 在线更新/延迟/公平性；不是为 180s 远程 API 设计 | 不做 TTT；用显式状态压缩，延迟可控 |
| D²-VLA | 双记忆 + 双频 KV cache | 改架构；没有物体图/主动感知；没有 rank 评测 | 不改基座；上下文层独立；RANK-CAL |
| Harness VLA | LLM agent + 冻结 VLA + 几何原语 | 引入第二个 LLM/agent；不是单模型最小方案 | 不用 LLM；确定性图/状态机 |
| GloVLA | 几何 transport + 局部 VLA | 双阶段策略；没有记忆/异常/评测 | 同一 VLA + 上下文门控；不训第二个局部策略 |
| HEX | 人形全身状态 + history tokens | 全身 loco-manipulation；不是桌面 32 任务 | 借历史 token 思想；加物体槽/异常/主动看 |

**共同空白**：这些工作都没有把“**排行榜的统计噪声**”当作系统设计的一部分。RANK-CTX 把评测和模型放在同一个闭环里：模型提出上下文干预，评测决定是否保留。

## 7. 竞赛策略：320 trials 是投资组合

### 7.1 算术

- 32 任务等权：一个任务成功率 +10pp → 全局 **+0.3125pp**。
- 人为干扰轴占每任务 2/10：human 成功率 +10pp → 全局 **+2pp**。
- 320 trials、`p=0.25`：全局 SE ≈ **2.42pp**；95% 区间 ≈ **±4.7pp**。
- 单任务 10 trials、`p=0.5`：SE ≈ **15.8pp**；95% 区间 ≈ **±31pp**。

**推论**：单任务排名不可信；全局 +2pp 也可能被噪声淹没。必须用配对/重复/序贯，而不是看一次全量。

### 7.2 任务组合

先验上，上下文杠杆最高的不是“最难的任务”，而是**过程长、状态多、可能被打断**的任务：

- 动态/遮挡：ConveyorSorting、RemovePinnedNote、ZipUp、PackBag、ToolboxStorage。
- 长程多阶段：ToolboxStorage（37.6s）、StorePaddle（34.1s）、SpellRobot（31.2s）、PackPhone（29.2s）、FoldTowel（25.8s）。
- 接触密集/插入：HangCup、PlugCharger、PlugInEthernet、Unlock、ArrangeTestTubes、SyringeWaterTransfer。
- 双臂协调：FoldTowel、ZipUp、StackBowls、OrganizePencilCase。

但这只是先验；**最终按 `P(Δ>0) × Δ / cost` 排序，不按任务难度标签排序。**

### 7.3 提交节奏

1. 第 1 周：安全基线（WLA 原样）锁 tie-break；G0/G1。
2. 第 2–3 周：C0 context card + CTX-SERVO；G2/G5；单任务通道。
3. 第 4 周：C1 adapter；G2 复测；只保留有配对证据的模块。
4. 第 5 周：BODY-LOOK/反射；G3/G4；安全门不过就砍。
5. 第 6 周：全量 G6；RANK-CAL 模拟；只提交一次主改动。
6. 任何时刻保留可回滚的上一版；不在截止前改未验证的代码。

## 8. 与第 12 轮 CHUNK-SERVO 的关系

### 0.4 创新点清单（本轮 v1，持续迭代）

> 状态：全部为“设计中/待验证”，没有一项已被真机验证。优先级按“竞赛杠杆 × 可行性”排序；P0 先做，P2 只在前置门通过后做。

#### P0-1 CTX-GRAPH：把上下文做成物体槽 + 相位 + 异常

- **动机**：VLA 只看到当前四路图和一句语言；33k 演示全是成功轨迹，没有“物体被挪走/夹空/遮挡/被打断”之后的状态。模型缺的不是历史长度，而是可查询的状态。
- **与现有方案差异**：MemoryVLA/RoboTTT 把记忆学进 bank/fast weights；CTX-GRAPH 是运行时、可解释、确定性的物体图，不训练第二个策略，不改 VLA 架构。
- **技术可行性**：头双目已标定，腕部有内参，`state_d435` 可恢复外参；物体跟踪用几何 + 模板 + Kalman，CPU 可跑；相位从夹爪/EE 信号无监督分段。
- **所需资源**：1 名工程师；CPU 每端口 <2 核；离线模板提取 2–3 GPU-days；不需要新增训练。
- **落地步骤**：32×20 episodes 相位挖掘 → 物体/受器模板 → 在线 Kalman/异常阈值 → G1 离线验证 → 单任务通道。
- **风险**：分割/关联错误会传播；低置信必须回退 VLA；透明/反光物体可能失败。

#### P0-2 CTX-CARD：把图压缩成 ≤128 token 的 VLA 上下文

- **动机**：直接把整段历史塞进 VLA 又慢又容易被无关帧淹没；需要把“阶段/物体/异常/目标”压成短上下文。
- **与现有方案差异**：不是 8K timestep 长上下文，也不是 LLM agent；是结构化 card，先 C0 零训练验证，再 C1 同一模型内小 adapter。
- **技术可行性**：C0 只改 `language` 字符串，零权重；C1 用 <10M cross-attention adapter，冻结 VLM、只训 action head，24GB 可跑。
- **所需资源**：1×24GB GPU；1 名工程师；C0 1 天，C1 3–5 天。
- **落地步骤**：C0 在 3 类任务做 10 对 A/B → 若有效上 C1 → 上下文 dropout 消融 → 防止模型只会读 card。
- **风险**：VLA 可能忽略文本；C1 可能过拟合 card；必须保留无 card fallback。

#### P1-3 BODY-LOOK：四足式小幅主动重观测

- **动机**：遮挡、人为干扰、透明物体时，继续执行只会错得更远；四足的做法是“不确定就挪身体看”，而不是硬走。
- **与现有方案差异**：不是大范围 base 运动/导航；只做桌面工作区内 waist/pivot 的 8–12 个候选动作，用信息增益 - 风险选择，确定性执行。
- **技术可行性**：`action.pivot [7]` 存在，但中间三维语义未知；P0 先静态标定哪些维度改变视角；安全包络 + 超时回中性位。
- **所需资源**：仿真 + 2 个真机任务；1 周；无需训练。
- **落地步骤**：标定 pivot → 仿真注入遮挡 → 真机 2 任务 → G3 安全/收益门；不过门默认关闭。
- **风险**：碰撞/超时/干扰任务；`pivot` 不可用则退化为“停 + 重规划”。

#### P1-4 PROPRIO-REFLEX：无力传感器下的夹空/滑移反射

- **动机**：API 没有力/触觉；夹空和滑移是桌面任务的高频失败，但演示里没有失败样本。
- **与现有方案差异**：借四足/CoPRE 的“无接触基线残差”思想，但不做力矩估计；用夹爪闭合签名 + EE 跟踪残差做更弱的代理，确定性触发。
- **技术可行性**：数据和 API 都有夹爪/EE 30Hz 信号；HangCup 已见 4.49→0.061 闭合签名；阈值可逐任务校准。
- **所需资源**：CPU；3 个任务（HangCup/ZipUp/Plug）；3–5 天。
- **落地步骤**：提取闭合/抬升签名 → 阈值/误触发统计 → 减速/重抓反射 → G4。
- **风险**：误触发/任务差异；只做“减速/停/重抓”，不做复杂力控。

#### P2-5 CTX-SERVO：由上下文门控的 5/8 步执行

- **动机**：CHUNK-SERVO 解决了 chunk 内无反馈，但不知道该对准什么、何时该停；上下文层提供目标与置信度。
- **与现有方案差异**：不是固定 30 步，也不是纯视觉伺服；`T_a` 选 5/8，由相位/不确定性/异常门控，目标来自物体/受器坐标系。
- **技术可行性**：腕部内参已确认；头双目可做 PBVS；WLA 相对 EE 可 compose 到 API 绝对位姿；确定性控制器。
- **所需资源**：1 名工程师；3 个任务；3–5 天；1×24GB GPU 用于 adapter 联调。
- **落地步骤**：动作 adapter → `T_a ∈ {5,8,15,30}` 配对 → 门控逻辑 → G5。
- **风险**：RTT/延迟、目标估计误差、chunk 切换抖动；必须保留 VLA 开环 fallback。

#### P0-6 RANK-CAL：私有配对评测与排名概率

- **动机**：公开榜单是预览/合成；10 次/任务的任务级排名是噪声；一次全量提交分辨不出 2–3pp。
- **与现有方案差异**：不是“看榜单改模型”；是分层贝叶斯 + 配对 A/B + 序贯 halving + 排名概率，用单任务不计分通道做唯一合规实验。
- **技术可行性**：单任务通道已存在；统计与 bootstrap 只需 CPU；不需要新模型。
- **所需资源**：1 名工程师；无 GPU；每周 1–2 天。
- **落地步骤**：安全基线 → 每任务 10–20 对 → 预注册 δ_min → 序贯淘汰 → 全量前 LCB 门。
- **风险**：样本小、对手先验宽、任务间相关；结论必须对先验稳健，不因一次排名波动改路线。

### 1.1 比赛规则（A）

官方参赛手册（飞书 docx，2026-10-31 通过 `r.jina.ai` 抓取；稳定拿到 §1.1–§2.2，后续章节可能截断，最终以官方页面为准）：

| 项 | 规则 |
|---|---|
| 模型 | 所有任务须基于**同一模型**完成，不得混合多个模型一起测试；模型类型不限 |
| 任务 | 32 项真实桌面任务，涵盖抓取、放置、双手协调 |
| 次数 | 每任务 10 次独立运行 |
| 泛化 | 5 类各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰 |
| 时限 | 单次真机执行上限 **180s**，超时记为失败 |

### 1.2 提交 API（A）

提交模板 README 与 `example_policy.py`（2026-10-31 复核）给出：

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640** |
| 观测本体 | 双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、`lower_body [15]`、语言 `str` |
| 动作空间 | `control_space` 仅 `"joint"` 或 `"ee"`，二者互斥 |
| 共享动作 | `action.left_gripper [1]`、`action.right_gripper [1]`、`action.pivot [7]` |
| EE 动作 | `action.left_ee_pose_gripper_base [6]`、`action.right_ee_pose_gripper_base [6]`（绝对目标位姿，xyz+rpy，base 系） |
| chunk | `action_chunk_size` 为 `int ≥1`，handshake 声明，提交内固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action` |
| token | `metadata.token` 握手校验；每次 `get_action` 的 `meta.token` 都要匹配 |
| 观测选择 | `obs_delta_indices` 的 key 决定发哪些观测；value 是 `≤0` 且严格递增的帧偏移 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile** |
| 监控 | evaluator 逐调用记录延迟、抖动、动作统计规律，作为结果可信度的一部分 |

**关键更正**：第 12 轮写“`action_chunk_size` 固定 30”不准确。README 明确它是 `int ≥1`，由选手声明、整个提交内固定；`example_policy.py` 用 **8**。30 只是 WLA 的默认训练/推理 horizon。**T_a 是提交级控制参数，不是模型默认值。**

**关键推论**：`T_a=30`、控制频率 30Hz 时，一次 `get_action` 后有约 1s 开环执行；chunk 内没有新观测，也没有打断机制。要利用上下文，必须把执行块降到 5–8 步，或把 VLA 规划与伺服执行拆成双频。控制频率未在 README 写死；本报告以 30Hz 为工作假设，必须实测。

| [Human2LocoMan](https://arxiv.org/abs/2506.16475)（2025-06） | 人→四足跨具身预训练；整体 +41.9%、OOD +79.7% | 借跨具身/模块化观测动作空间的方法论 |
| [CoPRE](https://arxiv.org/abs/2609.27381)（2026-09） | 无力传感器本体接触检测；G1 82.2% recall、5.5N 90% 检出 | 借“无接触基线残差”；挑战赛无力矩，只能用 EE/夹爪代理 |
| [Benchmark audit](https://arxiv.org/abs/2606.04233)（2026-06） | shortcut、统计显著性、渐进过拟合、数据源依赖 | 直接用“统计显著性”诊断私有评测 |
| [Retrieval study](https://arxiv.org/abs/2610.05492)（2026-10） | 检索方法没有一致赢家；随机检索也有非平凡成功率 | 检索只作上下文/gating，不单独控制 |
| [Colosseum V2](https://arxiv.org/abs/2605.27759)（2026-05） | VLA 在分布偏移下性能下降 | 支持“上下文/泛化”是主矛盾 |
| [HAF-VLA](https://arxiv.org/abs/2610.26584)（2026-10） | 人形全身分层 action flow：locomotion/head → waist → 双臂 | 支持“身体/视角先于手臂”的分层思想 |

### 1.7 未核实/未解决

- 实际控制频率（本报告以 30Hz 为工作假设；必须实测）。
- 网络 RTT 分布（同城/跨城/跨洲）。
- 提交次数限制。
- `action.pivot` 7 维逐维语义、范围、安全性。
- 人为干扰的具体时机/方式/是否允许接触机器人。
- 步骤分精确公式（公开手册只到 §2.2）。
- 官方 WLA 与挑战赛 API 的 `pivot` 语义是否完全一致。
- 挑战赛 32 任务是否都包含在 WLA 的 64 任务训练集中。

## 2. 问题形式化

### 2.1 评分与不确定性

总分：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

单任务标准误：

```math
\mathrm{SE}(p_t)=\sqrt{\frac{p_t(1-p_t)}{10}}.
```

| `p_t` | 单任务 SE | 95% 近似区间 |
|---:|---:|---:|
| 0.3 | 14.5pp | ±28.4pp |
| 0.5 | 15.8pp | ±31.0pp |
| 0.7 | 14.5pp | ±28.4pp |

全局 320 trials：

```math
\mathrm{SE}(S)=\sqrt{\frac{p(1-p)}{320}}.
```

| `p` | 全局 SE | 95% 近似区间 |
|---:|---:|---:|
| 0.25 | 2.42pp | ±4.7pp |
| 0.30 | 2.56pp | ±5.0pp |
| 0.50 | 2.80pp | ±5.5pp |

**结论**：一次 320-trial 全量提交分辨不出 2–3pp 的改进；单任务 10-trial 排名更不可信。必须做配对/重复/序贯。

人为干扰轴：

```math
\Delta S_{\mathrm{human}} = \frac{2}{10}\,\Delta p_h = 0.2\,\Delta p_h.
```

即 human 轴成功率 +10pp → 全局 **+2pp**。这是上下文层最直接的杠杆。

### 2.2 上下文状态

定义：

```text
C_t = (O_t, P_t, H_t, A_t, U_t)

O_t = {o_i}: 物体/受器槽
  o_i = (id, class, T_BO, v_O, Σ_O, visibility, grasp_width, last_seen, confidence)
P_t: 相位分布/阶段进度
H_t: 最近 K 步动作、夹爪开合、EE 速度、失败/重试计数
A_t: 异常标志（object_moved, occluded, slip, empty_grasp, unexpected_contact, human_interference）
U_t: 不确定性（Σ_O、相位熵、异常分数）
```

`T_BO` 是物体在 robot base 系的 6D 位姿；`Σ_O` 是其协方差。`P_t` 取 8 个原语：`reach, grasp, lift, transport, align, insert/fasten, release, retreat`。`H_t` 用固定长度 ring buffer，避免每端口内存增长。

### 2.3 相位图

从 33k 演示无监督挖相位，不依赖人工标注：

- **观测信号**：EE 速度/加速度、夹爪开合及导数、物体-EE 相对位姿、头部/腕部图像变化、EE 跟踪残差。
- **分段**：对每条演示做多变量 change-point detection（PELT/贝叶斯在线变点），把夹爪闭合、EE 抬升、接触前减速作为强边界；再用 HSMM 平滑成 8 原语。
- **任务语法**：每个任务是一条相位图路径，例如 `HangCup: reach→grasp→lift→transport→align→hook→release→retreat`；`ToolboxStorage` 是多个 `reach→grasp→transport→place` 循环 + `close/lock`。
- **在线**：状态机 + guard；guard 用几何/本体阈值，不用学习策略。相位熵高时触发 BODY-LOOK 或 VLA fallback。

### 2.4 主动感知的信息增益

把物体位姿近似为高斯 `N(μ, Σ)`。候选身体动作 `u` 的期望信息增益：

```math
IG(u) = H(o_t\mid z_{1:t}) - \mathbb{E}\left[H(o_{t+1}\mid z_{1:t},u)\right],
```

高斯熵 `H = 0.5 log((2πe)^3 |Σ|)`；用测量 Jacobian `J` 与噪声 `R` 近似后验协方差：

```math
Σ' = (Σ^{-1} + J^\top R^{-1} J)^{-1}.
```

选择：

```math
u^\* = \arg\max_{u\in U_{\mathrm{body}}} \left[ \operatorname{tr}(Σ) - \operatorname{tr}(Σ') - \lambda R(u) \right],
```

只在 `IG > IG_min` 且安全包络通过时执行。`U_body` 只包含 8–12 个候选：waist yaw ±5°/±10°、pitch ±3°/±6°、pivot height ±1cm、base yaw ±3°；不走路。

### 2.5 单模型合规

| 模式 | 内容 | 合规性 | 风险 |
|---|---|---|---|
| **C0** | 只把 context card 拼进 `language`；不改权重 | 最安全 | VLA 可能忽略文本 |
| **C1** | 同一 WLA 内加 <10M context adapter，联合微调 action head | 仍是同一模型 | 需证明不是第二策略 |
| **C2** | CTX-GRAPH/BODY-LOOK/CTX-SERVO 确定性控制器 | 不是学习模型 | 需在 README 说明 |
| **禁止** | 每任务一个模型、模型集成、第二个 VLM/策略、评测时在线学习 | 违规 | 不碰 |

**合规底线**：唯一可学习策略是 WLA；新增层要么是确定性控制器，要么是同一 WLA 内的小 adapter。提交 README 明确写出“single policy + deterministic context shell”。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
Evaluator (N ports 8765..8765+N-1)
   │  websocket: obs / action chunk
   ▼
Per-port PolicyService (CPU)
   ├─ Context Service
   │   ├─ CTX-GRAPH
   │   ├─ CTX-CARD
   │   ├─ BODY-LOOK planner
   │   ├─ PROPRIO-REFLEX
   │   └─ CTX-SERVO
   ├─ action adapter (WLA 54D ↔ API 21D)
   └─ VLA client (async, batched)
         │
         ▼
Shared VLA server (GPU)
   UnifoLM-WLA-1.0 + optional context adapter
```

- 每端口独立 `ContextService`，`reset()` 清空 `O/P/H/A/U`；共享 GPU 只做无状态推理。
- 图像/上下文缓存按端口隔离；不跨 episode 泄漏。
- 上下文服务目标：<2 CPU 核、<2GB RAM、单步 <10ms；VLA 推理异步批处理。
- 网络线程与推理线程分离；动作 chunk 带时间戳，防止旧 chunk 覆盖新观测。

### 3.2 接口契约

```python
# 伪代码：不是官方 API 实现
class ContextService:
    def reset(self, task: str, token: str):
        self.task = task
        self.ctx = ContextState.initial(task)
        self.history.clear()

    def get_action(self, obs, meta):
        assert meta["token"] == self.token
        self.ctx.update(obs)                  # CTX-GRAPH
        if self.ctx.should_reobserve():
            body = self.body_look.plan(self.ctx)
            if body.safe:
                return self.servo.wrap(body, horizon=3)
        card = self.card.encode(self.ctx)      # ≤128 tokens
        plan = self.vla.get_plan(obs, card)    # 30-step plan, async
        action = self.servo.execute(plan, self.ctx, horizon=5)
        return self.adapter.to_api(action)
```

### 3.3 `get_action` 决策顺序

1. **协议检查**：`meta.token`、观测 key、shape、dtype。
2. **上下文更新**：物体槽、相位、异常、不确定性。
3. **安全门**：若异常/低置信/碰撞风险 → 停、hold、BODY-LOOK 或 VLA replan；不在错误目标上伺服。
4. **上下文门控**：
   - 接触密集 & 低不确定性 → CTX-SERVO（5 步）。
   - 运输/接近 & 低不确定性 → 直接执行 VLA chunk。
   - 高不确定性/异常 → 重观测/重规划。
5. **动作适配**：WLA 相对 EE → 绝对 EE；gripper 直通；pivot 从 base/waist/height 组合；裁剪到 API 范围。
6. **返回** `(T_a, ...)`，`T_a` 与 handshake 一致；index 0 先执行。

### 3.4 CTX-GRAPH 更新

**物体测量**：

- 头双目：校正后 `left/right` 去畸变 → 视差 → 深度 → base 系点云；用 `state_d435` 恢复头相机外参。
- 腕部：内参 + 手眼外参 → 近距 3D；手眼外参一次性标定（标定板/已知物体）。
- 语义候选：演示模板 + 颜色/边缘/形状 + VLA cross-attention；**不引入第二个学习检测器**。
- 数据关联：最近邻 + 类别/颜色/尺寸；失败时新建槽，旧槽保留 `last_seen`，协方差增长。

**预测**：

```math
T_{B O,t+1}^{-} = T_{B O,t} \exp(\hat{v}_O \Delta t),\qquad
Σ_{t+1}^{-} = F Σ_t F^\top + Q.
```

**异常**：

```math
e_{\mathrm{obj}} = \| T_{B O}^{\mathrm{pred}} \ominus T_{B O}^{\mathrm{meas}} \|_{Σ},
```

- `object_moved = e_obj > τ_obj`。
- `occluded = visible_ratio < τ_vis`。
- `slip = \|v_O - v_{EE}\| > τ_slip`（抓取后）。
- `empty_grasp = |w_g - w_{\mathrm{demo}}| > τ_w` 且夹爪闭合后无抬升。
- `unexpected_contact = \|T_{B EE}^{cmd} - T_{B EE}^{obs}\| > τ_{ee}` 在自由空间相位。
- `human_interference = object velocity spike + 新进入工作区的类手区域 + 动作中断`（启发式，不做人手检测模型）。

**HangCup 示例（B，单 episode）**：右夹爪 4.49 → 0.061（f80）闭合，抬升后 0.154（f100+）；左夹爪恒定 4.507。这个闭合签名可作为“抓取已发生/仍在夹持”的本体证据；但不能假设所有任务同一量纲，必须逐任务校准。

### 3.5 CTX-CARD

```text
[TASK] Hang the cup on the marked spot.
[PHASE] align (3/8), progress 0.62
[OBJECTS] cup @ (0.42,0.03,0.12) vis=0.81; rack_hook @ (0.45,0.10,0.18) vis=0.93
[LAST] grasp=ok; lift=12cm; slip=0.02; retries=0
[ANOMALY] none
[GOAL] hook opening at pixel (312,204); approach -z; gripper width 6.2cm
```

- 最多 128 token；数字保留 2–3 位有效数字；不塞整段历史。
- `C0`：拼到 `language`；`C1`：编码成 8–32 token 注入 action head；`C2`：目标裁剪图，stretch。
- 训练时随机 dropout 上下文，避免模型过度依赖 card；推理时若 card 缺失，退回纯 VLA。

### 3.6 BODY-LOOK

**触发**：

- `U_t` 高（物体协方差大/相位熵高）。
- `visibility` 低或连续 `object_moved`。
- 连续两次 `empty_grasp`/`slip`。
- 人为干扰后目标丢失。

**候选动作**：

| 动作 | 范围 | 目的 |
|---|---|---|
| waist yaw | ±5°/±10° | 避开遮挡、看侧面 |
| waist pitch | ±3°/±6° | 看桌面/高处 |
| pivot height | ±1cm | 改变视角高度 |
| base yaw | ±3° | 最后手段，谨慎 |

**执行**：

1. 安全位检查（双臂收拢、无接触、物体不在手）。
2. 生成 8–12 个候选；用 `IG - λR` 排序；只执行 top-1。
3. 3 步小动作 + 停 + 重观测；超时 1.5s 回中性位。
4. 若 `pivot` 语义未标定，BODY-LOOK 默认关闭，只做“停 + 重规划”。

**四足启发**：不是把 G1 当四足，而是借“本体接触/滑移估计、视觉退化时靠历史、主动挪身体看、扰动后先恢复稳定”。Human2LocoMan 证明跨具身/人类先验对四足操作有效（整体 +41.9%、OOD +79.7%），但本方案不训练四足策略，只迁移原则。

### 3.7 CTX-SERVO

目标：

```math
T_{B EE}^{d} = T_{B F}\,T_{F EE}^{d},
```

`F` 是物体/受器坐标系（杯架钩、网口、拉链滑块、锁孔、瓶盖、碗沿）。误差：

```math
e = \log\left((T_{B EE}^{d})^{-1} T_{B EE}^{obs}\right),
\qquad
u = \mathrm{clip}(K_p e + K_d \dot{e}).
```

- 执行 `H_s=5` 步；每步更新上下文；下一步重新看。
- 门控 `g = 1[phase∈contact] · 1[U_t<u_max] · 1[no anomaly]`；`g=0` 时 hold/replan。
- 滑移/夹空：先减速/停，再决定重抓或继续；不引入第二个学习策略。
- `T_a` 选 5/8；VLA 规划 horizon 可以仍是 30，但 API 每次只返回 `T_a` 步。

### 3.8 动作适配（WLA 54D → 挑战赛 21D）

- WLA EE 动作是相对当前 EE 的 xyz+rotvec：

```math
T_{B EE}^{cmd} = T_{B EE}^{obs}\,\exp(\Delta\xi).
```

- 转成 API 的绝对 `xyz+rpy`；注意 rotvec→rotation matrix→rpy 的奇异性，必要时做连续性展开。
- `gripper` 直通；确认数据/API 的量纲（演示约 0–4.6，API 目标范围需实测）。
- `pivot`：从 WLA 的 base/waist/height 组合；中间三维未公开，先中性；P0 标定。
- 所有输出裁剪到 API 范围；非法值回退 hold。

## 4. 离线数据编译

### 4.1 相位挖掘

- 每条演示抽取：EE 位姿、夹爪宽度、物体/受器相对位姿、动作、时间戳。
- 多变量变点检测；以夹爪闭合、EE 抬升、接触前减速为强边界；HSMM 平滑。
- 人工只做抽检，不做全量标注；用 32 任务 ×20 episodes 验证相位 F1。
- 产出：每个任务的相位图、每相位时长分布、进入/退出 guard 阈值。

### 4.2 物体/受器模板

- 从演示关键帧提取任务相关物体/受器的 2D/3D 模板：颜色直方图、边缘、尺寸、抓取宽度、接近方向。
- 在线用模板匹配 + 立体几何；失败时用 VLA attention 候选。
- 不训练检测器；模板库是数据资产，不是第二个模型。

### 4.3 异常库

- 从演示中挖“正常”的夹爪闭合/EE 跟踪/物体运动分布。
- 人为构造扰动（仿真/回放注入）生成异常样本：物体移动、遮挡、夹空、滑移、延迟。
- 异常阈值用分位数 + 任务自适应；不用学习分类器。

### 4.4 规模估算

- 相位/物体模板：每任务 20–50 个 exemplar，总计数百 MB。
- 特征索引：按需采样，不一次性解码 169h 视频；离线特征提取 2–3 GPU-days。
- 在线 context service：<2GB RAM/端口；物体槽 <20；历史 <2s。

## 5. 排行榜与评测

### 5.1 榜单不可靠的六条证据

1. `generated_from: gen_leaderboard.py`。
2. `step ~ success` 回归 `R² > 0.999999`，最大残差 `<0.006`。
3. 成功率非 10 次整数倍（27.29%、27.85%、38.43%）。
4. 详情视频全部占位。
5. 页面底部“即将发布”。
6. 跨模型任务相关仅 0.098（若任务难度真实，应正相关）。

### 5.2 统计设计

**分层贝叶斯**：

```math
y_{t,j}\sim\mathrm{Bernoulli}(p_t),\qquad
\mathrm{logit}(p_t)=\mu+a_t+b,
```

`a_t ~ N(0, σ_a^2)` 是任务难度，`b ~ N(0, σ_b^2)` 是方法效应；弱信息先验，避免 10 次试验的极端估计。报告后验均值、95% 区间和 `P(Δ>0)`。

**配对 A/B**：

- 同一任务、同一初始条件，baseline/intervention 交替；至少 10 对。
- 二分类用 McNemar；连续指标用 paired bootstrap。
- 预注册：`δ_min=5pp`（单任务）或 `δ_min=1pp`（全局）；只看区间下界，不看均值。

**序贯 halving**：

1. 32 任务各 2 对，淘汰 `P(Δ>0)<0.2` 的任务。
2. 剩余任务各 4 对，淘汰 `P(Δ>0)<0.5`。
3. 剩余任务各 8–10 对，做最终决策。
4. 预算按 `EVPI` 分配，优先“效应可能大且不确定”的任务。

**排名概率**：

- 对手分数用宽先验（不是预览榜单精确值）；Monte Carlo 采样 `P(rank≤k)`。
- 结论必须对先验稳健；若不同先验下结论翻转，不做提交决策。

### 5.3 任务组合

- 32 任务等权：一个任务 +10pp → 全局 **+0.3125pp**。
- 人为干扰轴 2/10：human +10pp → 全局 **+2pp**。
- 320 trials、`p=0.25`：全局 SE **2.42pp**。
- 先验优先：动态/遮挡、长程多阶段、接触密集、双臂协调；但最终按 `P(Δ>0)×Δ/cost` 排序。
- 不把“最难”当“最值得做”；等权意味着任何任务的 10pp 增益相同，选成本最低/置信最高的。

### 5.4 提交节奏

1. 第 1 周：WLA 原样安全基线，锁 tie-break；G0/G1。
2. 第 2–3 周：C0 context card + CTX-SERVO；G2/G5。
3. 第 4 周：C1 adapter；只保留有配对证据的模块。
4. 第 5 周：BODY-LOOK/反射；G3/G4；安全门不过就砍。
5. 第 6 周：全量 G6；RANK-CAL 模拟；只提交一次主改动。
6. 任何时刻保留可回滚的上一版；不在截止前改未验证代码。

| 相位挖掘 | 32×20 episodes | 相位 F1、边界误差 | F1 ≥0.8 |
| 物体跟踪 | 回放 + 注入遮挡 | 位置误差、可见性校准 | <2cm（工作区） |
| 异常检测 | 注入移动/遮挡/夹空/滑移 | AUROC、误触发率 | AUROC ≥0.8，误触发 <10% |
| 上下文卡压缩 | 人工标注 200 条 | 信息保留率、token 数 | ≤128 token，关键字段 100% |

### 6.2 仿真

- 用官方 IsaacLab/MuJoCo + G1 URDF 搭轻量桌面场景；注入位置/遮挡/背景/移动物体/延迟。
- 不做完整 sim-to-real 策略训练；只做 BODY-LOOK/CTX-SERVO/异常阈值的风洞。
- 评估：恢复率、碰撞、超时、动作平滑度；sim 成功率不能直接预测真机。

### 6.3 真机单任务

- 选 6 个任务：HangCup（接触）、ZipUp（拉链）、PlugInEthernet（插入）、ConveyorSorting（动态）、ToolboxStorage（长程）、RemovePinnedNote（扰动）。
- 每任务 10–20 对 baseline/intervention；固定初始条件；交替执行。
- 记录：成功率、步骤分、时长、碰撞、人工干预次数、p99 延迟。

### 6.4 全量

- 32 任务 ×10；先跑 baseline，再跑 intervention；RANK-CAL 先验模拟。
- 只有全局 `LCB(ΔS)>0` 且 `ΔS≥1pp` 才提交。
- 全量结果不用于在线调参；只用于最终决策。

### 6.5 消融

| 消融 | 目的 |
|---|---|
| C0 vs no card | 上下文是否被 VLA 使用 |
| C1 vs C0 | adapter 是否值得 |
| BODY-LOOK on/off | 主动重观测是否有效 |
| 滑移反射 on/off | 本体反射是否有效 |
| `T_a=5/8/15/30` | 执行块与反应性 |
| 相位 oracle vs 估计 | 相位误差的代价 |
| 物体图 oracle vs 估计 | 物体图误差的代价 |

### 6.6 门 G0–G7

| 门 | 通过标准 | 失败动作 |
|---|---|---|
| G0 协议 | 10/10 无错误；p99 <200ms | 先修接口 |
| G1 离线 | 相位 F1 ≥0.8；物体误差 <2cm | 降级相位 only |
| G2 上下文 | 3 类中 2 类 ≥10pp；无任务掉 >5pp | 改 C1 或砍 |
| G3 BODY-LOOK | 恢复率 ≥15pp；碰撞 0；时长 +<5% | 关闭 |
| G4 反射 | 重抓 ≥20pp；误触发 <10% | 退回视觉 |
| G5 伺服 | 5/8 优于 30，接触 ≥10pp | 保留 8 |
| G6 全量 | 全局 ≥+2pp，LCB>0 | 回滚 |
| G7 复盘 | 单位工程时间收益 >基线 | 剪枝 |

## 7. 资源与时间表

| 资源 | 估计 |
|---|---|
| GPU | 1×24GB（WLA action-head/C1 adapter 微调）；2×A10/A100 用于离线特征提取（可选） |

## 8. 风险与合规

| 风险 | 概率 | 影响 | 缓解 |
|---|---:|---:|---|
| 物体图误差传播 | 中 | 高 | 置信度门控；低置信回退 VLA；只在相位明确时用图 |
| BODY-LOOK 碰撞/超时 | 中 | 高 | 安全包络；静态标定；仿真先行；默认关闭 |
| `pivot` 语义不明 | 高 | 高 | P0 单任务标定；标定前中性值；不依赖它做核心收益 |
| context card 被 VLA 忽略 | 中 | 中 | C0 先测；无效上 C1；仍无效则砍 |
| 单模型规则解释风险 | 低 | 高 | 只用同一 WLA + 确定性控制器；README 明确；不集成 |
| 评测噪声误判 | 高 | 高 | 配对 A/B；bootstrap；序贯；预注册门槛 |
| 人为干扰协议未知 | 高 | 中 | 多时机注入；以“检测-停-重定位”为主；不假设固定脚本 |
| 远程 RTT/延迟 | 中 | 中 | 5/8 步 chunk；CPU 轻量；p99 监控；降增益 |
| 过拟合预览榜单 | 中 | 高 | RANK-CAL；不看榜单任务排名；只信配对区间 |
