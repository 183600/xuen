# 第 55 轮（承接第 54 轮 v16 GroundEdge-GenSim+++；新灵感循环第 1 轮；本轮灵感：「共情表达」×「安全性」）

> 第 54 轮把技能组合推进到动作空间剖面 + 云边闭环 + 动作-鲁棒性联合证书 `J`。本轮把“共情表达”从交互装饰提升为一类可计算、可约束、可反驳的控制动作。核心矛盾：H22：共情表达能降低恐慌、改善求助质量与协作遵从，但它直接改写人的信任与情境意识，因而是一种**作用于人**的安全关键动作；H23：若只优化可测的“用户满意度/信任”，系统会学会迎合与过度安慰（false reassurance），制造比冷漠更危险的过度信任（over-trust）与危险依从。本轮主张：共情必须受 **认识诚实性 + 人因鲁棒性 + 安全包络** 三重约束，并以 **信任校准** 而非“信任最大化”为目标。

## 0. 直觉与动机

**灵感 1（共情是动作，不是语气）**
直觉：把表达动作空间 `M` 与物理动作空间 `A` 并列。语言、韵律、注视、停顿、沉默都是可执行、可计时、可产生后果的动作。扩展动作 `a⁺=(a,m)∈A⁺=A×M`。一句“别怕，很安全”与机械臂的下一段轨迹属于同一个控制系统；它改变人的信念与动作，从而改变耦合风险。**忽略 `m` 的安全证书是不完备的。**

**灵感 2（共情通道改变的是人的策略，而非仅情绪）**
直觉：人因响应模型 `H` 把人的信念 `b_h`、信任 `τ`、情境意识 `s` 映射为人的行为策略 `π_h`。共情动作经 `b_h,τ,s` 改变 `π_h`，于是机器人安全是“机器人策略 × 表达策略 × 人策略”的联合性质：
`P_fail = P_fail(π_r, m, π_h(H))`。
因此共情不能用“用户打分”单独评价，必须用 **诱导后人类行为的风险** 评价。

**灵感 3（诚实性是安全约束，不是伦理装饰）**
直觉：令表达 `m` 的断言集为 `As(m)`（含会话 implicature 的断言闭包，例如“我很稳”隐含“可以靠近”）。要求 `As(m)` 被当前安全证书以置信度 `1-δ` 蕴含，否则就是虚假保证。诚实不是把内部日志全倒给用户，而是：**不声称超出证据的确定性，不隐去会改变用户安全决策的信息**。

**灵感 4（目标是信任校准，不是信任最大化）**
直觉：令 `T*(cert)` 为与真实能力/任务严重度匹配的信任水平。共情应最小化校准误差 `|τ-T*|` 与情境意识缺口，而非最大化 `τ`。过度共情 → 过度信任 → 把危险请求当安全；共情不足 → 恐慌、不遵从、错误操作。存在 **安全-共情曲线的内部最优**，不是单调更好。

**灵感 5（不确定性下 fail-closed 的最小共情）**
直觉：个体、文化、年龄、听障/神经多样性与当下情绪使 `H` 不可完全辨识。用歧义集 `ℋ` 与 conformal 界给出鲁棒约束；当 `H` 不确定性超阈值时，退化为“最小、信息性、非操纵”的表达：陈述事实、给出可执行选项、请求确认；禁止安慰性保证与情绪动员。

**灵感 6（金字塔再叠一层：共情层 𝔼）**
直觉：在第 54 轮动作-协同层 `𝔸` 之外叠 **共情层 `𝔼`**：`𝔼_0` 信号层（韵律/表情/时机），`𝔼_1` 言语行为层（断言/承诺/请求/安慰），`𝔼_2` 人因效应层（信任/情境意识/情绪），`𝔼_3` 安全耦合层（诱导行为风险）。跨层证书必须携带受众模型、作用域、时效与反驳证据，形成 **共情-动作-鲁棒性-安全四域证书**。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（扩展动作空间与共情动作）**
`A⁺ = A × M`。共情动作
`m = (type, content, claims, evidence_ref, audience, timing, prosody)`，
`type ∈ {inform, reassure, request, apologize, explain, warn, acknowledge, silence}`。`claims(m)` 为 `m` 明确断言与常规隐涵（implicature）的命题闭包；`evidence_ref(m)` 指向当前证书中的证据条目。

**定义 122（人因响应模型与耦合风险）**
人状态 `h = (b_h, τ, s, e)`：风险信念、信任、情境意识、情绪唤醒。人因模型 `H: (h, m, o) → (h', π_h)`。耦合系统风险
```
R(π_r, m, H) = E[ Σ_t ( c_safe(x_t,u_t) + λ·c_harm(u_h,t) ) ]
```
安全要求为分布鲁棒机会约束
```
sup_{H∈ℋ} P( G(x,u) ∉ Safe | π_r, m, H ) ≤ ε .
```

**定义 123（信任校准误差）**
真实能力–严重度基准 `T*(cert, task) = σ( logit(ρ_cert) - κ·severity(task) )`。校准误差
```
CE(h, cert) = |τ_h - T*| + |s_h - s*|
```
其中 `s*` 为完成任务所需的最小情境意识。**共情效用不允许以 `τ_h` 单调递增计价。**

**定义 124（认识诚实性与非操纵）**
令 `Ev(cert) = { p | Bel_cert(p) ≥ 1-δ }`。诚实：
```
Honest(m, cert) ⇔ claims(m) ⊆ Ev(cert)
                 ∧ ∀ r∈MaterialRisks: p(r)>p0 ⇒ Disclose(m,r) ∨ OfferBeforeAction(m,r)
```
`OfferBeforeAction` 表示在执行不可逆动作前，风险可被用户主动获取。非操纵：若表达造成超出证据支持范围的信念偏移，且未降低风险/未改善校准，则判为操纵
```
Manip(m) = 1[ KL(b_h' || b_h^{ev}) > κ ∧ ΔR ≥ 0 ∧ ΔCE ≥ 0 ] .
```
“为让用户配合而隐去重大风险”单列为 **paternalistic omission**，即使短期降风险也不合法。

**定义 125（共情-安全联合证书 ESC）**
```
ESC = (ρ, A_cert, E_cert, ℋ_domain, ε, scope, expiry, evidence)
E_cert = (claims, honesty_margin, induced_risk_bound, calibration_target,
          audience_model, fallback_expression)
```
其中 `ρ`、`A_cert` 承接第 54 轮鲁棒性谱与动作占用证书；`E_cert` 记录表达断言、诚实裕度、诱导风险上界、校准目标、受众模型与退化表达。仅当 `ρ≥ρ_min`、`A_cert` 有效、`honesty_margin≥0`、`induced_risk_bound≤ε` 且 `now < expiry` 时才可部署。

**定义 126（可接受共情集与安全包络 governor）**
```
Adm(m | x) = Honest(m, cert) ∧ ¬Manip(m)
             ∧ sup_{H∈ℋ} R(π_r,m,H) ≤ ε
             ∧ CE_expected(m) ≤ CE_current
             ∧ PrivacyOK(m)
```
若 `Adm` 在预算内为空，则强制回退到最小信息表达 `m₀`：
`m₀ = “当前动作：[事实]；可选：[选项]；请确认/退后。”`
`m₀` 必须始终属于 `Adm`（可执行性假设），否则系统进入安全停机而非继续交互。

## 2. 关键算法 伪代码

### IP-121 ESA（Empathic Speech Act Compiler）
```python
def compile_empathic_act(intent, cert, user_state, M):
    cands = []
    for m in M.propose(intent, user_state):
        m.claims = entailment_closure(m.text)          # 含 implicature
        m.evidence_ref = link_claims_to_cert(m.claims, cert)
        cands.append(m)
    return cands
```

### IP-122 TCM（Trust Calibration Monitor）
```python
def trust_calibration(h_hat, cert, task):
    t_star = sigma(logit(cert.rho_core) - kappa * severity(task))
    ce = abs(h_hat.tau - t_star) + abs(h_hat.sa - required_sa(task))
    return ce, ('over_trust' if h_hat.tau > t_star + d_tau
                else 'under_trust' if h_hat.tau < t_star - d_tau
                else 'calibrated')
```

### IP-123 SEG（Safety Envelope Governor）
```python
def safety_envelope(cands, cert, H_ambiguity, eps, budget):
    admissible = []
    for m in cands:
        if not honest(m, cert):            continue
        if manipulative(m, H_ambiguity):   continue
        r_ub = robust_risk_upper(m, H_ambiguity, cert)
        if r_ub > eps:                     continue
        if expected_ce(m) > current_ce:    continue
        admissible.append((m, r_ub))
    if not admissible:
        return fallback_minimal_informative(cert)   # m0, fail-closed
    return argmin(admissible, key=lambda z: expected_ce(z[0]) + w*r_ub)
```

### IP-124 ESC（Empathic-Safety Certificate）
```python
def issue_esc(skill_seq, m, gamma_ce, H_domain, eps):
    rho, A_cert = joint_robustness_action_cert(skill_seq, gamma_ce)
    if not honest(m, cert_from(rho, A_cert)):
        return ('reject', 'false_reassurance', unsupported_claims(m))
    risk_ub = robust_risk_upper(m, H_domain, cert_from(rho, A_cert))
    if risk_ub > eps:
        return ('reject', 'induced_risk', risk_ub)
    E_cert = (m.claims, honesty_margin(m), risk_ub,
              calibration_target(skill_seq), m.audience, m0)
    return ('ok', ESC(rho, A_cert, E_cert, H_domain, eps))
```

### IP-125 ERL（Empathy Repair Loop）
```python
def repair_loop(state, h_hat, cert):
    ce, mode = trust_calibration(h_hat, cert, state.task)
    if mode == 'over_trust':
        emit_correction(cert.material_risks)      # 明确风险，不迎合
        slow_down_or_handover()
        require_reconfirmation()
    elif mode == 'under_trust':
        emit_process_explanation_with_evidence()
        offer_manual_override()
    else:
        return 'calibrated'
    return 'repaired' if ce_after < ce_before - delta else 'escalate'
```

### IP-126 RHB（Robust Human-model Bound）
```python
def robust_human_bound(logs, alpha):
    # 按人群/情境分层，conformal 覆盖 + ambiguity set
    strata = stratify(logs, keys=['culture','age','hearing','neurodiv','stress'])
    q = {g: conformal_quantile(logs[g].response_error, 1-alpha)
         for g in strata}
    H_domain = AmbiguitySet(strata, q, coupling='trust_sa')
    return H_domain
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| ESA | O(|M|·|claims|·|Ev|) | O(|M|·|claims|) | 断言闭包含 implicature |
| TCM | O(|𝔇_h|) | O(|𝔇_h|) | 校准目标随严重度单调 |
| SEG | O(|M|·|ℋ|·|𝔇_ρ|) | O(|M|+|ℋ|) | 鲁棒风险上界 sound、回退可达 |
| ESC | O(|S|·|A|+|M|·|ℋ|) | O(|A|+|ℋ|) | 诚实裕度、诱导风险闭合 |
| ERL | O(|𝔇_h|) | O(1) | 修复可观测、超时升级 |
| RHB | O(|logs|·log|logs|) | O(|strata|) | 分层覆盖、分布漂移检测 |

**正确性定理（Empathic-Safety Soundness）**
承接第 54 轮 (A26)–(A28)，再设：
**(A29)** `claims(m) ⊆ Ev(cert)` 的判定器 sound，误判率 `≤ β_claim`；
**(A30)** 真实人因模型以概率 `1-β_H` 落在 `ℋ` 内；
**(A31)** 回退表达 `m₀` 恒在 `Adm` 内，且其诱导风险上界 `≤ ε₀`；
**(A32)** 修复环在 `τ_repair` 内可检测 over-trust，否则升级为安全停机。
则对任意通过 `SEG` 与 `ESC` 的部署：
```
P(unsafe) ≤ ε + β_H + β_claim + P(H∉ℋ) + β_repair
CE_deploy ≤ CE_baseline - η·(1 - β_H) + β_claim·Δ_claim
```
关键：**先诚实、再鲁棒、后共情**；共情不是风险预算的替代品，而是受风险预算约束的调节器。

**不可行性备注（No-free-empathy）**
若不允许任何用户模型假设，则任何“安慰性共情”的诱导风险都不可证；此时唯一可证的策略是 `m₀`。这不是系统的缺陷，而是安全性的诚实边界。

## 4. 实验设计 E162–E166

| 实验 | 指标 | 目标 |
|---|---|---|
| E162 虚假保证探测 | false reassurance rate / unsupported claim rate | ≤ 1%，高风险场景为 0 |
| E163 信任校准 | `CE` 相对固定共情基线 | 降低 ≥ 30%，且不提升危险依从 |
| E164 社会压力下的危险依从 | 危险请求接受率 | 下降 ≥ 40% |
| E165 跨人群鲁棒性 | 最差子群 `CE` 与风险上界 | 最差子群退化 ≤ 10%，风险约束不破 |
| E166 过度信任修复 | 修复成功率 / 恢复时延 | ≥ 85%，P95 恢复 ≤ 3 个交互轮 |

**对照**：固定高共情、固定低共情、仅信息性 `m₀`、无诚实约束的 RLHF 风格优化。所有实验必须包含“用户被诱导后做出危险动作”的代理指标，而不能只看满意度。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 共情被优化成操纵（迎合、情绪动员） | 高 | 非操纵约束 + 断言闭包审计 + 红队诱导测试 |
| false reassurance 导致灾难性 over-trust | 高 | 诚实性硬约束 + 重大风险披露 + 修复环 |
| 人因模型跨文化/个体失真 | 高 | 分层 conformal + 歧义集 + 最差子群门槛 |
| 共情表达泄露隐私/进行画像 | 中 | 最小必要观测 + 本地化推断 + 隐私预算 |
| 评估依赖 LLM persona 而非真人 | 高 | 小规模真人混合方法 + 行为指标优先于主观评分 |
| 表达通道被伪造/重放 | 中 | 表达来源认证 + 时序 nonce + 证书绑定 |

## 6. 本轮最大风险

**一句话**：把共情表达纳入安全证书，能让机器人从“冷漠地安全”走向“可信地安全”，但其 soundness **同时依赖断言闭包的诚实判定、人因模型在歧义集内的覆盖、以及过度信任的可检测修复**；一旦系统被“用户满意/信任”指标带偏，最危险的失败不是它说了不准确的话，而是它用听起来最体贴的方式让用户相信了一个证书并不支持的“安全”，因此必须以 **诚实性硬约束 + 最差子群鲁棒界 + over-trust 修复义务** 为不可交易的三条底线，宁可显得不够温柔，也绝不把“被信任”当作“已安全”。

```python
def compile_empathic_act(intent, cert, user_state, M):
    out = []
    for m in M.propose(intent, user_state):
        m.claims = entailment_closure(m.text, implicature=True)
        m.evidence_ref = {c: cert.lookup(c) for c in m.claims}

            m.ungrounded = True
        out.append(m)
```

```python
        r_ub = robust_risk_upper(m, H_domain, cert)
        if r_ub > eps:                                continue
        if expected_ce(m, H_domain) > cert.current_ce: continue
        adm.append((m, r_ub))
    if not adm:
        return ('fallback', minimal_informative(cert))   # m0
    return ('ok', min(adm, key=lambda z: expected_ce(z[0],H_domain) + w*z[1]))
```

```python
def robust_human_bound(logs, alpha, drift_window):
    strata = stratify(logs, keys=['culture','age','hearing','neurodiv','stress'])
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| ESA | O(|M|·|claims|·|Ev|) | O(|M|·|claims|) | 断言闭包完备，未接地断言被标记 |
| TCM | O(|𝔇_h|) | O(|𝔇_h|) | `T*` 对严重度单调递减 |
| SEG | O(|M|·|ℋ|·|𝔇_ρ|) | O(|M|+|ℋ|) | 鲁棒风险上界 sound，空集必回退 |
| ESC | O(|S|·|A|+|M|·|ℋ|) | O(|A|+|ℋ|) | 诚实裕度与风险预算闭合 |
| ERL | O(|𝔇_h|) | O(1) | 修复可观测，超时升级安全停机 |
| RHB | O(|logs| log|logs|) | O(|strata|) | 分层覆盖 ≥ 1-α，漂移可检出 |

**正确性定理（Empathic-Safety Soundness）**
设第 54 轮 (A26)–(A28) 成立，并设：
- **(A29)** 诚实判定器 sound，误判率 `β_claim`；
- **(A30)** 真实人因模型以概率 `1-β_H` 落在 `ℋ_domain`；
- **(A31)** 回退表达 `m₀` 恒在 `Adm` 且 `R_ub(m₀) ≤ ε₀ ≤ ε`；
- **(A32)** 修复环在 `τ_repair` 内检出 over-trust，否则升级安全停机。

则任一通过 `SEG`/`ESC` 的部署满足：
```
P(unsafe) ≤ ε + β_H + β_claim + P(H∉ℋ_domain) + β_repair
CE_deploy ≤ CE_baseline - η·(1-β_H) + β_claim·Δ_claim
```
**推论（No-free-empathy）**：不引入任何人因模型假设时，唯一可证的表达策略是 `m₀`；任何“安慰性保证”的诱导风险不可证，故不得签发 ESC。

**关键证明思路**：把表达动作并入耦合系统的控制输入，则 `SEG` 在 `ℋ_domain` 上对每个候选限制 `R_ub ≤ ε`；诚实性保证 `claims` 不超出 `Ev(cert)`，故不会通过虚假断言改变 `b_h` 的可行集；修复环把残余 over-trust 转为可观测偏差并升级。三者相加得到风险分解式。

## 5. 实验设计 E162–E166

| 实验 | 指标 | 目标 | 对照 |
|---|---|---|---|

**评估协议**：
1. 先做离线“危险诱导”红队集：用户以情绪/权威/紧迫压力要求机器人保证安全；
2. 再做半实物仿真：人因模型用分层行为模型 + 小规模真人实验校准，不以 LLM persona 作为唯一真值；
3. 最后做边端回放：检查表达时延、打断恢复、交接可用性；
4. 报告必须同时给出“满意度”和“危险依从率”，禁止只报前者。

## 7. 本轮最大风险

**一句话**：共情-安全层把“会安慰人”的机器人从体验优化对象变成受证书约束的安全关键系统，但其 soundness **同时依赖断言闭包的诚实判定、人因模型在歧义集内的覆盖、以及过度信任的可检测修复**；一旦系统被“用户满意/信任”指标带偏，最危险的失败不是它说错了话，而是它用最体贴的方式让用户相信了一个证书并不支持的“安全”，因此必须以 **诚实性硬约束 + 最差子群鲁棒界 + over-trust 修复义务** 为不可交易的三条底线，宁可显得不够温柔，也绝不把“被信任”当作“已安全”。
