## 1. 直觉与动机（两个灵感的碰撞）

### 灵感 1（群体智能 → 不是多模型集成，而是同一模型的「动作粒子群」+ 一个共享大脑的机器人群体）

**直觉**：流匹配/扩散策略天然能从一个观测生成**多个**动作块——只换初始噪声即可。单个样本可能落在坏模态（抓偏、绕远），但一群样本里「多数派」往往是对的；更妙的是，群体**分歧本身**就是一个免费的不确定性传感器：当粒子分成两簇（左抓/右抓），说明此刻策略在犹豫，正是最该触发恢复或延长思考的时刻。另一方面，F21 告诉我们评测现场本身就是 N 台机器人并发——一个「群体」共享同一套模型权重与只读检索库（大脑），但每台机器人的记忆必须隔离（不能跨 episode 学习，这是诚信红线）。

**严谨定义 1（动作粒子群与共识）**：设策略为生成式动作块分布 \(p_\theta(a_{1:T_a}\mid o)\)，\(a\in\mathcal A^{T_a}\)。独立采 K 个粒子 \(\{a^{(k)}\}_{k=1}^K\)（同一 \(\theta\)、不同噪声种子）。定义归一化距离
\[
d(a,b)^2=\frac1{T_a}\sum_{t=1}^{T_a}\Big(\frac{\|p_t^a-p_t^b\|^2}{\sigma_p^2}+\frac{\angle(R_t^a,R_t^b)^2}{\sigma_R^2}+\frac{(g_t^a-g_t^b)^2}{\sigma_g^2}\Big).
\]
以阈值 \(\delta\) 建图（边 \(d\le\delta\)），取最大连通簇 \(C\)，输出**簇内 medoid**
\[
a^\*=\arg\min_{a^{(i)}\in C}\sum_{j\in C} d(a^{(i)},a^{(j)}),
\]
离散度 \(U=\frac1{|C|}\sum_{j\in C}d(a^\*,a^{(j)})\)，次峰占比 \(B=|C_2|/K\)。**关键：用 medoid 而非均值**——多峰抓取下均值会产生物理不可行的「折中抓取」，medoid 保证输出仍是模型真实样本。

**严谨定义 2（群体边界）**：群体只允许两层——L_intra：同一 episode 内同权重多粒子；L_infra：跨端口共享只读模型/检索索引与批处理。禁止 L_cross：跨 episode 共享状态、经验或在线适应。L_cross 既违反 F21 的状态隔离，也触碰「评测期不学习」红线。

**核心反直觉点**：群体智能在这场比赛里不是「训练很多模型投票」，而是**在一个 episode 内把一次前向变成 K 次采样的一次小型群体决策**；模型仍然只有一个。

### 灵感 2（实时推理 → 延迟不是约束，是一笔被浪费的测试时算力预算；但固定块长让它是「有代价的预算」）

**直觉**：官方不按秒计分，但 F22 给出一个被多数队伍忽略的事实：评测器执行完整个动作块才回来要下一块，所以两次调用之间有约 \(T_a/f\) 秒。这段时间不是「必须尽快返回」的压力，而是「可以花掉」的预算——多采几个粒子、多走几步去噪、或做一次轻量校验。反过来，F20/F24 也给出代价：块长全局固定且运行期不可改，块内是**开环承诺**，越长越不反应、越短算力越少。于是实时推理的真正问题不是「怎么更快」，而是**「全局块长 T_a 与每块算力 K 的联合最优分配」**。

**严谨定义 3（块预算与 anytime 策略）**：设控制频率 \(f=15\)Hz，安全系数 \(\rho\in(0,1)\)，单块截止期
\[
D=\rho\,T_a/f.
\]
设 K 个粒子的实测耗时 \(c(K)\)（同批前向可次线性）。可行集 \(\mathcal K(D)=\{K: c(K)\le D\}\)。一个 anytime 策略在任意 \(t\le D\) 可返回当前最优 \(a^\*_t\)，且期望质量随 K 单调不降。在「主模态概率 \(p>1/2\)、模态内直径 \(\le\delta\)」的假设下，K 个粒子漏掉主模态的概率 \(\le(1-p)^K\)——这给出样本数的 PAC 式下界：\(K\ge \ln(1/\alpha)/\ln(1/(1-p))\) 时以 \(1-\alpha\) 概率锁定主模态。

**严谨定义 4（全局块长选择）**：对 32 个任务，设任务 i 的反应性约束 \(T_a\le T_i^{\max}\)（接触段短、搬运段长），单块效用 \(u_i(T_a,K)\)。全局只能选一个 \(T_a\)，于是
\[
T_a^\*=\arg\max_{T_a}\ \mathbb E_{i\sim\mathcal T}\Big[\max_{K\in\mathcal K(\rho T_a/f)} u_i(T_a,K)\Big],
\]
约束为所有接触密集任务不违反 \(T_i^{\max}\)。这是一个「一块定全局」的单点决策，必须用离线回放扫出 Pareto 前沿。

**核心反直觉点**：实时推理的正确用法不是压缩延迟，而是**把未用满的块预算换成测试时算力**；而固定块长意味着这笔预算与「反应性」直接对冲。

### 两个灵感的统一

群体采样需要算力，实时推理提供算力；实时推理的固定块造成开环承诺，群体采样的离散度恰好给出「该不该在块末进入恢复」的信号。两者合起来是一个闭环：
**块预算 → 采 K 个粒子 → 共识输出 + 离散度 → 高离散度则触发 I5 恢复 / 缩短下一块行为（在固定 T_a 内做安全收尾）**。
本轮结论：**比赛的第二个胜负手不在「训练更强的策略」，而在「把每块闲置算力和 N 端口并发服务面用对地方」——这是数据引擎之外的推理侧杠杆。**

## 2. 对前两轮痛点的增量修订

- **P5（时间压力）重定义**：从「推理要快」改为「块预算是可花费资源」；速度本身不计分，延迟稳定性才进可信度（F23）。
- **新增 P9（开环承诺风险）**：T_a 全局固定，块内无法响应扰动；长块省算力但盲，短块反应快但算力少。T_a 是单点决策。
- **新增 P10（N 端口争用）**：共享后端在 N 台机器人并发时 p99 会抬升；批处理省显存但可能伤延迟稳定性（F21/F23）。
- **新增 P11（测试时随机性）**：群体采样引入动作方差；聚合不当会同时伤成功率与可信度，必须有 K=1 确定性回退。
- **P2（泛化缺口）**：群体共识在高不确定性（未见物品/位置偏移）episode 上应比标称 episode 获益更大——这是可检验的预测。
- **P4（无触觉）**：离散度可作为「接触前犹豫」的视觉替代信号，部分弥补无力/触觉通道。
- **P1/P3/P7/P8** 维持。

## 3. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

- **Q9（群体共识是否只在难例上有效）**：K 粒子共识相对 K=1 的成功率增益，是否随评测轴偏移量（位置/外观/干扰物）单调增大？何种聚合（均值/medoid/最大簇 medoid）在多峰抓取上不产生不可行动作？\(\delta,\tau_u\) 能否按任务族标定？
- **Q10（块长-算力联合最优）**：32 任务全局唯一的 \(T_a\) 取多少？块预算 \(D=\rho T_a/f\) 在 N 端口并发下的真实 p99 是多少？评测器的「per-step latency」到底按调用还是按块摊销？能否通过逐 episode 重连拿到逐集 T_a？
- **Q11（群体搜索配置）**：用群体演化搜索测试时配置（K、\(\delta\)、\(\tau_u\)、\(T_a\)、聚合方式）能否超过人工调参？把同一套搜索扩展到数据/增广配置时，必须付出多少次短程代理训练，L0 代理与真机增益的相关性何时 >0.6？

## 4. 设计原则（新增 PR6–PR8，PR1–PR5 保留）

- **PR6 预算转化律**：每一毫秒未用满的块预算，都必须转化为「更多粒子」或「更多去噪步」中边际效用更高的一项；不允许让预算空转。
- **PR7 群体边界律**：群体只允许 L_intra（同 episode 同权重多粒子）与 L_infra（跨端口只读共享 + 批处理）；L_cross（跨 episode 状态/经验共享、在线适应）一律禁止。与 PR2 单模型边界互补。
- **PR8 开环承诺律**：固定 T_a 下，每个块都必须以「可恢复的安全末态」结束（速度收敛、夹爪状态明确、不处于不可逆临界点），使下一块有纠错余地；块长按最坏扰动而非平均扰动选。
- PR1–PR5 保留（第 1–2 轮 §4）。

## 6. 本轮最大风险

**一句话**：整个 I10/I6 都押在「块级预算可被使用」这一前提上——若评测器把每次 `get_action` 响应硬性卡在 ~66ms（而非按 T_a 摊销），群体采样直接失效；必须在写任何训练代码前用 `run_client.py` 实测调用间隔与超时判据，否则本轮一半方案归零。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I10 群体采样共识推理（新） ★★★★★

- **动机**：流匹配/扩散策略对同一观测可生成多个动作块，但默认只取一个；在泛化轴偏移与接触临界点上，单样本方差大（P2/P9）。同时，块级执行窗口（F22，\(T_a/f\approx1.07\)s）有大量未用预算。群体采样把「多余算力」换成「对多模态动作的鲁棒选择」。
- **与现有方案差异**：不是多模型集成（违反单模型/成本），而是**同一权重、同一 episode 的 K 个粒子**；不是简单平均（会把左抓/右抓平均成不可行动作），而是**最大簇 medoid**；不是额外训练一个 critic，而是用**粒子间几何离散度**做免费不确定性信号。
- **技术可行性**：高。只需在推理 sampler 上换噪声种子并批采样；共识是 K≤8 的小规模聚类，CPU 微秒级；无需改训练。
- **所需资源**：无额外训练；推理显存随 batch K 线性增加但 K≤8 可控；1 人周工程 + 1 GPU 日标定。
- **落地步骤**：①在离线回放上扫 K∈{1,2,4,8} 与 \(\delta\)；②实现 medoid 共识与离散度；③块预算 anytime 循环；④高离散度触发 I5 恢复；⑤本地 N 客户端压测；⑥真机 top 配置确认。
- **风险**：硬性 per-call 延迟限制（见 §6 风险句）；多峰下 medoid 仍可能选错模态（缓解：离散度触发保守收尾 + I9 检索先验偏置）；随机性伤可信度（缓解：K=1 确定性回退 + 固定种子策略 + 延迟平滑）。

**形式化**：策略 \(p_\theta(a_{1:T_a}\mid o)\)；采 K 粒子；距离 \(d\) 为位置/旋转/夹爪的归一化组合；单链接聚类取最大簇 \(C\)；输出 \(a^\*=\arg\min_{a^{(i)}\in C}\sum_{j\in C}d(a^{(i)},a^{(j)})\)；离散度 \(U=\frac1{|C|}\sum_{j\in C}d(a^\*,a^{(j)})\)；次峰占比 \(B=|C_2|/K\)。置信判据：\(U\le\tau_u\) 且 \(B<0.3\)。高不确定时不平均，直接输出最大簇 medoid 并标记恢复。

### I6 v3 实时预算调度器 ★★★★★

- **动机**：F20/F22 把「每步 66ms」重写为「每块 \(T_a/f\)」；F21 要求 N 端口并发且状态隔离；F23 把延迟稳定性纳入可信度。旧 I6 只讲「更快」，没讲「预算怎么花、并发怎么稳」。
- **本轮升级**：
  1. **块级流水线**：评测器执行块 k 的 \(T_a\) 步期间，服务端可完成块 k+1 的采样/去噪（若采用异步预测）或在本次调用内把预算花满；至少做到观测反序列化、图像 resize、tokenizer 与模型前向重叠。
  2. **截止期感知 anytime**：以 \(D=\rho T_a/f\) 为硬截止；先 K=2 采样，置信则立即返回，不置信且有余量再加样本；到点返回当前最优。
  3. **N 端口连续批处理**：每端口独立队列 + 独立 episode 状态；请求按截止期排序，短窗口聚合成 batch；负载高时按端口下调 K（凹效用贪心注水）。
  4. **预算旋钮联合优化**：`image_resize`（480×640→240×320）与 `obs_delta_indices`（最少相机/最少历史）省下的编码时间，全部回流给 K 或去噪步（PR6）。
- **与现有方案差异**：旧方案把延迟当上限；本点把延迟当预算，并显式处理 N 端口争用与延迟稳定性。
- **技术可行性**：高。复用官方 model_server 的 websocket/msgpack 模式（F12）；批处理与队列是常规 serving 工程。
- **所需资源**：2×A100 80G 共享后端；1 人周 serving 工程；本地 N 客户端压测脚本。
- **落地步骤**：①测单块 c(K) 曲线；②实现 deadline anytime；③实现 per-port 状态隔离与连续批处理；④压测 N=1/2/4/8 的 p50/p99；⑤`run_client.py` 全流程门禁。

### 1.1 块预算与全局 T_a 选择

```python
# 事实：get_action 每次返回 T_a 步，评测器执行完整块才再调用（F20/F22）
# 单块名义执行时间 ≈ T_a / f_control；可用预算取安全系数 rho
def chunk_budget_ms(T_a, f_control=15.0, rho=0.6):
    return rho * (T_a / f_control) * 1000.0

# 例：T_a=16 -> 1066ms * rho；rho=0.6 -> 640ms
# 例：T_a=8  -> 533ms  * rho；rho=0.6 -> 320ms
# 例：T_a=4  -> 267ms  * rho；rho=0.6 -> 160ms
# 全局只能选一个 T_a：按任务反应性 T_i_max 与效用 u_i(T_a,K) 的加权和选
def choose_global_Ta(tasks, rho=0.6):
    best = None
    for Ta in (4, 8, 16):
        if any(Ta > t.T_max for t in tasks):     # 接触密集任务不允许长块
            continue
        D = chunk_budget_ms(Ta, rho=rho)
        K = max_k_within(D)                       # 由 §1.2 的 c(K) 曲线
        score = sum(t.weight * t.u(Ta, K) for t in tasks)
        best = max(best, (score, Ta, K))
    return best                                   # (score, Ta, K)
```

**关键**：\(T_a\) 不是超参，是「反应性 vs 算力」的全局单点决策。接触密集任务（ZipUp/PlugCharger/SyringeWaterTransfer）给 \(T_i^{\max}\) 较小；搬运/整理类允许 16。若全局只能选一个，预期折中在 8 附近，需用 L0 回放验证。

### 1.2 群体采样 + medoid 共识 + anytime

```python
import time, math
from collections import defaultdict

class SwarmConsensus:
    def __init__(self, cfg):
        self.cfg = cfg  # K0, Kmax, dK, delta, tau_u, mode_share, rho

    def dist(self, a, b, st):
        # a,b: (T_a, d) 动作块；st: 数据集统计量（位置/旋转/夹爪尺度）
        dp = (((a[..., :3] - b[..., :3]) / st.sigma_p) ** 2).sum(-1)
        dr = ((geodesic_angle(a[..., 3:6], b[..., 3:6])) / st.sigma_R) ** 2
        dg = (((a[..., 6:] - b[..., 6:]) / st.sigma_g) ** 2).sum(-1)
        return float(((dp + dr + dg).mean()).sqrt())

    def consensus(self, samples, st):
        n = len(samples)
        D = [[self.dist(samples[i], samples[j], st) if i != j else 0.0
              for j in range(n)] for i in range(n)]
        parent = list(range(n))
        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]; x = parent[x]
            return x
        for i in range(n):
            for j in range(i + 1, n):
                if D[i][j] <= self.cfg.delta:
                    parent[find(i)] = find(j)
        groups = defaultdict(list)
        for i in range(n):
            groups[find(i)].append(i)
        groups = sorted(groups.values(), key=len, reverse=True)
        C = groups[0]
        medoid = min(C, key=lambda i: sum(D[i][j] for j in C))
        U = sum(D[medoid][j] for j in C) / max(1, len(C))
        B = (len(groups[1]) / n) if len(groups) > 1 else 0.0
        return samples[medoid], U, B

    def confident(self, U, B):
        return U <= self.cfg.tau_u and B < self.cfg.mode_share

    def act(self, model, obs, st):
        t0 = time.perf_counter()
        D = chunk_budget_ms(T_A, rho=self.cfg.rho) / 1000.0
        k = self.cfg.K0
        samples = model.sample_chunks(obs, k=k)       # 同权重、不同噪声；尽量批采样
        best, U, B = self.consensus(samples, st)
        while (not self.confident(U, B)
               and k < self.cfg.Kmax
               and time.perf_counter() - t0 < D):
            step = min(self.cfg.dK, self.cfg.Kmax - k)
            samples += model.sample_chunks(obs, k=step)
            k += step
            best, U, B = self.consensus(samples, st)
        self.last_uncertainty = (U, B)                 # 免费信号 -> I5/I8
        if not self.confident(U, B):
            self.request_recovery = True               # 触发 I5，不在此块硬切
        return best                                    # 长度固定 T_a，可 anytime 返回
```

**为什么用 medoid**：均值在两模态（左抓/右抓）下会产生两模态之间的「穿越」轨迹，可能碰撞；medoid 一定是模型真实样本，且对离群粒子鲁棒。代价是每次要算 \(O(K^2)\) 距离，K≤8 可忽略。

**样本复杂度直觉**：主模态概率 p、漏检概率 \((1-p)^K\)。p=0.5 时 K=4→6.25%、K=8→0.39%；所以 K=4–8 是性价比区间。

### 1.3 N 端口 deadline 调度（严格状态隔离）

```python
class PortState:                 # 每端口独立，禁止跨端口读写
    def __init__(self):
        self.history = deque(maxlen=32)
        self.retrieval_prior = None
        self.last_uncertainty = None
        self.recovery = False

class DeadlineScheduler:
    def __init__(self, n_ports, model, rho=0.6):
        self.model = model
        self.q = {p: [] for p in range(n_ports)}
        self.state = {p: PortState() for p in range(n_ports)}   # 隔离
        self.rho = rho
        self.shared_index = load_readonly_index()              # 只读共享，OK

    def submit(self, port, obs, deadline):
        self.q[port].append((deadline, obs))

    def adaptive_K(self, load, D):
        # 凹效用贪心：负载越高，单端口 K 越小；总 batch 受显存/截止期约束
        K_total = max_k_within(D / max(load, 1))
        return max(1, min(K_total, 8))

    def run(self):
        while any(self.q[p] for p in self.q):
            ready = [(dl, p, obs) for p in self.q for (dl, obs) in self.q[p]]
            if not ready:
                continue
            ready.sort()                                  # 截止期优先
            batch = ready[:self.max_batch]
            for _, p, _ in batch:                         # 取走请求
                self.q[p].pop(0)
            D = min(dl - time.time() for dl, _, _ in batch)
            K = self.adaptive_K(len(batch), D)
            outs = self.model.batch_sample([obs for _, _, obs in batch], k=K)
            for (_, p, obs), samples in zip(batch, outs):
                st = self.state[p]                        # 只读本端口状态
                best, U, B = consensus(samples, st_stats)
                self.q[p].result = best
```

**调度目标**：\(\max\sum_p u_p(K_p)\)，约束每端口 \(c(K_p,\sum K)\le D_p\)。\(u_p\) 对 K 凹（收益递减），故按「边际效用/毫秒」贪心注水即可近似最优；负载高时自动降 K，保证 p99。

## 2. 实验设计（分级消融 + 明确 kill 判据）

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0 | E1 共识增益、E2 离散度 AUROC、E3 聚合方式、E4 T_a×K Pareto、E5 群体搜索、E6 N 端口压测、E7 恢复触发 | 离线/本地（近免费） | 见下方逐项判据 |
| L1 | top 2 配置 × 2 任务 × 各 2 次真机 | 单任务通道 | 成功率/步骤分 ≥ 离线预测 50%，p99 稳定 |
| L2 | 最终配置全量确认 | 正式评测 | 不回归标称任务，泛化轴有增益 |

**逐项实验与 kill 判据**：

- **E1（共识是否只在难例上有效）**：留出 episode 施加考纲轴偏移（位置/外观/干扰物/背景），比较 K=1 vs {2,4,8}。预测：偏移越大，共识增益越大。**Kill**：K=4 增益 <2% 且延迟成本 >20% → 修剪 I10。
- **E2（离散度是否预测失败）**：用 \(U\) 对留出 episode 的失败/步骤损失算 AUROC。**Kill**：AUROC<0.6 → 关闭不确定性门控，仅保留共识。
- **E3（多峰聚合安全）**：构造左右抓/绕过障碍的双模态样本，比较 mean/medoid/largest-mode-medoid 的不可行动作率与碰撞率。**Kill**：medoid 不可行动作率不显著低于 mean → 重新设计距离/阈值。
- **E4（T_a×K Pareto）**：T_a∈{1,2,4,8,16} × K∈{1,2,4,8}，离线回放 + 扰动注入，画「反应性-成功率-延迟」前沿。产出全局 T_a 候选。
- **E5（群体搜索 vs 人工）**：P=16/G=8 免费层搜索，与人工 v1.1 配置比；记录离线-真机相关性。**Kill**：8 个真机点后 Spearman<0.4 → 回到人工。
- **E6（N 端口压测）**：本地起 N∈{1,2,4,8} 个 `run_client`，测 p50/p99、吞吐、K 自适应；并注入跨端口状态污染测试，验证隔离。**Kill**：N=4 时 p99>D → 下调 K 或增加后端。
- **E7（离散度触发恢复）**：在 3 个弱任务（PlugCharger/ZipUp/PourOutMedicine）上比较「固定恢复」vs「离散度触发恢复」的步骤分与误触发率。
- **E8（门禁）**：`run_client.py` 全流程 + 动作 shape/健康度 + 延迟平滑 + token；0 拒绝动作。
