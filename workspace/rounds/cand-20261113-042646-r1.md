## 2. 两个灵感词：先直觉，再严谨定义

### 2.1 「开源硬件」——不是造一个 G1，而是造“任务级物理孪生”

**直觉**：比赛最大的不公平是“你摸不到真机、也不敢高频试”。但**扰动-恢复这条轴关心的是物体状态**（盖子开了没、拉链合了没、碗叠上没），而不是人形本体的行走/平衡。既然 Dex1-1 只是平行夹爪，我们完全可以用 ~$500 的开源硬件，在桌面上复刻“同一批物体 + 同一套扰动 + 同一组几何判据”，得到一个**可反复折腾的物理真值台**。它不需要像 G1，只需要像“这张桌子”。

**严谨定义（OSHW-T，Open-Source-Hardware Task Twin）**：一个物理台架 $T=(O,S,A,D)$：
- $O$：与任务同构的物体集合（同类别、同尺寸量级、可贴 ArUco/AprilTag）；
- $S$：观测集合（顶置全局快门相机 + 腕部相机 + 可选力/称重传感），用于计算几何谓词；
- $A$：执行器集合（SO-101 follower 做粗操作；第二臂/二轴龙门做“扰动施加器”）；
- $D$：由 `human_*` 文本编译来的扰动程序集合（开→合、合→开、叠→拿、插→拔、移底座）。

**能力边界（必须写死）**：$T$ 是**物体状态保真**，不是**本体动力学保真**。它可用于（a）造扰动-恢复数据、（b）验证几何谓词、（c）粗技能演示；不可用于（d）Dex1 细接触力控、（e）人形全身动力学。任何用 $T$ 得出的结论标注为 **OSHW 代理**，与 GSO 代理同等对待。

### 2.2 「多模态大模型」——不做在线裁判，做离线“编译器 + 教师”

**直觉**：v2 把 MLLM 摆在评测回路里，既贵又可能违规。正确的用法是把 MLLM 放在**开发期**：它读规则文本 + 演示视频，把非结构化任务说明编译成可执行谓词/技能图/扰动脚本（编译器）；再把密集进度与“被撤回”事件标注到海量视频上，蒸馏进单模型（教师）。**部署时只留一个模型。**

**严谨定义（R2E，Rulebook-to-Executable）**：编译器 $C:(t, s, g, V)\mapsto(S, P, G, D)$，其中 $t$ 为任务名/描述，$s$ 为 `scoring_points`（含权重），$g$ 为 `generalization` 文本，$V$ 为若干演示视频；输出有序子目标 $S=\{s_1..s_G\}$（权重与 $s$ 对齐）、可执行谓词集 $P$、技能 DAG $G$、扰动程序 $D$。目标：在谓词可执行、可在演示上自测通过的约束下，最大化对计分点的覆盖。

**严谨定义（PAL，Progress-Aware single model）**：单一参数化函数 $f_\theta:(o_{t-h:t}, l)\mapsto(A_{t:t+k}, \pi_t^{1:G}, h_t)$，同时输出动作块、各子目标进度 logits、回归风险（被撤回 hazard）；所有评测期计算只经 $f_\theta$（多头允许），不调用任何外部模型/服务。训练可用任意离线教师（MLLM）蒸馏。

**合规工作假设（必须向主办方确认）**：规则约束的是**提交的评测期策略**，不是开发期工具链；因此离线用 MLLM 编译规则/标注数据应属允许。若规则连开发期也禁止他模型，则 R2E/PAL 的教师环节需退回人工/规则，但仍可用其“单模型多头”结构。

## 3. 瓶颈假设（更新）

- **H1（最高杠杆，延续）**：人为干扰会主动反向消耗步骤分，而公开数据零覆盖；“检测进度被撤回→重做”仍是同时救成功率与步骤分的唯一机制。
- **H2（新，本轮核心）**：**恢复轴是“物体状态中心”，不是“本体中心”**。由 Dex1-1=平行夹爪推得：便宜的开源平行夹爪台架足以校准大部分恢复逻辑，真机只需做细接触锚点。
- **H3（新）**：v2 的验证器瓶颈不是“模型不够强”，而是“结构没被编译成可执行谓词”。MLLM 离线编译能把手写 32 任务的成本降一个量级，并天然产出技能图与扰动脚本。
- **H4（新）**：把验证从“外部模型”改成“同骨干辅助头”，可在几乎不增延迟的前提下同时满足单模型合规与逐步验证——比“外部 VLM 裁判 + 合规风险”严格占优（若蒸馏损失可控）。
- **H5（修正）**：G1 的 Gazebo 路线不可依赖；物理神谕应建在 MuJoCo（官方 MJCF）与开源硬件台架上，Gazebo 仅备选。
- **H6（可推导）**：最优块长随“撤回风险”下降而增大——$k^\*=\sqrt{2c_{rt}/(c_m p_t)}$，即 $k^\*\propto p_t^{-1/2}$（推导见产物区 §4）。这把“实时性”和“验证”统一成一个决策。

## 1. 旗舰深潜：UIP-16 · PAL（Progress-Aware single model）

### 1.1 机制
一条共享多模态骨干（视觉-语言编码 + 动作块头），加三个轻量辅助头：
- `action_head`：输出长度 $k$ 的动作块 $A_{t:t+k}$；
- `progress_head`：输出 $G$ 个子目标的进度 logits $\pi_t^{1:G}$（与计分步一一对齐、权重来自 `scoring_points`）；
- `regression_head`：输出“当前进度被撤回”的风险 $h_t\in[0,1]$；
- （可选）`conf_head`：置信度，用于 UACS/ CSG。

**评测期只有这一个网络**，因此“自验证”不引入第二个模型、不引入外部调用——直接消灭 v2 的“单模型合规”软肋。

### 1.2 严谨定义
- 子目标状态机：对子目标 $g$，$p_t^g\in\{0,1\}$ 表示完成与否；`done` 当 $p_t^g=1$；`regressed` 当窗口内 $p_t^g$ 从 1 掉回 0 且 $h_t>\tau_r$。
- 进度伪标签由离线教师给出：MLLM 读视频 + 任务文本，输出稠密分段 $\{(g, [t_a,t_b])\}$ 与撤回事件。
- 单模型合规判据（工作定义）：存在单一 $f_\theta$（允许多头），使评测期所有计算均为 $f_\theta$，无外部模型/服务调用。训练期教师不受此限（**须向主办方确认**）。
- 训练目标：
$$\mathcal{L}=\mathcal{L}_{act}+\lambda_p\mathcal{L}_{prog}+\lambda_r\mathcal{L}_{reg}+\lambda_c\mathcal{L}_{cal}$$
其中 $\mathcal{L}_{prog}$ 为教师伪标签的逐子目标 BCE，$\mathcal{L}_{reg}$ 为撤回事件 BCE，$\mathcal{L}_{cal}$ 校准置信度（如 focal/temperature）。

### 1.3 为什么严格优于 v2
| 维度 | v2 外部 VLM 裁判 | v3 PAL 内部头 |
|---|---|---|
| 单模型合规 | 有风险 | 结构上满足 |
| 在线延迟 | 多一次大模型往返 | 与动作块同一次前向 |
| 逐步验证 | 每 k 步调用外部 | 每次 `get_action` 自带 |
| 失败模式 | 服务不可用/限流 | 蒸馏偏差（可校准） |

### 1.4 落地
1. R2E（UIP-17）先生成子目标与权重；
2. MLLM 教师在公开 32 数据集 + UIP-12′ 生成数据上打稠密进度/撤回标签；
3. 蒸馏进 PAL（单骨干多头）；
4. 用 UIP-19 RLC 在 OSHW/MuJoCo/真机上校准阈值 $\tau_r$。

## 2. UIP-17 · R2E（Rulebook → Executable）

### 2.1 机制
把非结构化的 `info.json`（任务名、`scoring_points`、`generalization`）+ 少量演示视频，编译成**可执行规格**：
- 有序子目标 $S$（权重与计分点一致）；
- 谓词集 $P$（几何/接触/关系/视觉四类）；
- 技能 DAG $G$；
- 扰动程序 $D$（由 `human_*` 文本生成“反向撤回”脚本）。

### 2.2 输出 schema（示例）
```json
{
  "task": "T26_plug_in_ethernet",
  "subgoals": [
    {"id": 1, "weight": 30, "desc": "grasp cable",
     "predicate": {"type": "contact", "expr": "gripper_holds('rj45')"},
     "obs": ["wrist_left"], "needs_force": true},
```

## 4. 实时性：UIP-13″ · UACS（不确定性自适应块长）

### 4.1 推导（把验证与实时统一）
设单次往返成本 $c_{rt}$，块长 $k$；设每步发生“进度被撤回”的风险 $p_t$，开环下平均检测延迟 $\approx k/2$，漏检代价 $c_m$。单位时间期望成本：
$$J(k)=\frac{c_{rt}}{k}+\frac{c_m\,p_t\,k}{2}$$
令 $J'(k)=0$：$-\dfrac{c_{rt}}{k^2}+\dfrac{c_m p_t}{2}=0$
$$\boxed{k^\*=\sqrt{\frac{2c_{rt}}{c_m\,p_t}}\ \propto\ p_t^{-1/2}}$$
**读法**：PAL 的回归头 $h_t$（或进度熵）越高 → 块越短、重观测越密；越安全越省往返。这比 v2 的“分阶段固定 k”更有依据，且能与 `metadata` 的**全局最大 k** 兼容（每次返回 $\le k^\*$ 步）。

### 4.2 实现约束
- metadata 只在握手时定一次 ⇒ 声明全局 `K_MAX`，运行期返回 $\le K_{MAX}$ 的块；严格按形状/ dtype / 索引 0 先执行。
- 与 UIP-15 CSG 联动：$h_t$ 高 + 抖动预算紧张时，优先“重做”而非“继续”。

## 7. UIP-19 · RLC（Reality Ladder Calibration）

### 7.1 阶梯与代价
| 梯级 | 神谕 | 成本 | 保真对象 | 典型用途 |
|---|---|---|---|---|
| R0 | 真机 G1 | 极高（稀缺） | 全部 | 最终锚点/验收 |
| R1 | OSHW-T | 低 | 物体状态/粗操作 | 谓词真值、扰动恢复、粗演示 |
| R2 | MuJoCo | 低 | 本体+接触近似 | 顺序/结构、大规模 rollout |
| R3 | 视频回放 | 极低 | 仅已有轨迹 | 回归测试、不评新动作 |
| R4 | MLLM 裁判 | 低 | 语义先验 | 冷启动/弱标注 |

### 7.2 信任判据
在少量真机校准集上，令 $s_i^j$ 为第 $j$ 个神谕给第 $i$ 条 rollout 的步骤分，定义保真度：
$$\rho_j=\mathrm{Spearman}\big(s^{j}, s^{0}\big)$$
对某决策 $D$（如“方案 A 是否优于 B”），仅当 $\rho_j\ge\tau_D$ 且覆盖率 $\ge\kappa_D$ 时才信任 $O_j$；否则只允许其用于**排序/筛选**，不得用于**绝对成败**。R1/R2 先用 R0 少量样本校准，再作为高频廉价锚点反哺训练（自举）。

```python
# UIP-16 PAL: 单骨干多头（评测期唯一模型）
class PAL(nn.Module):
    def forward(self, obs, lang):
        z  = self.backbone(obs, lang)      # 4 路相机 + 语言
        A  = self.action_head(z)           # (K_MAX, act_dim)
        pi = self.progress_head(z)         # (G,) 逐子目标进度
        h  = self.regression_head(z)       # 被撤回风险 [0,1]
        c  = self.conf_head(z)             # 置信度
        return A, pi, h, c

# UIP-01″ + UIP-13″: 部署回路
class RHPVD_v3:
    def reset(self):
        self.g = 0; self.redo = 0
    def get_action(self, obs):
        A, pi, h, c = self.model(obs, self.lang)      # 一次前向，无外部调用
        if self._done(pi, self.g):
            self.g += 1; self.redo = 0
        elif h > self.tau_r and self.redo < self.max_redo:
            self.redo += 1                            # 检测到被撤回 → 重做
        k = self.uacs(h)                              # k* ∝ 1/sqrt(p_t)
        return A[:k]
```
