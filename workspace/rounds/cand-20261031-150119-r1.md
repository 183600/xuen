# 第 13 轮 · GAZEL：把指令编译成「角色槽」，用 Gazebo 做 N-way K-shot 语义风洞，用 k-shot 原型把没见过的物体绑到像素

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮承接第 10 轮 **FACT-VLA**、第 11 轮 **GEO-RESIDUAL**、第 12 轮 **CHUNK-SERVO**；三个灵感词是「Gazebo」「指令泛化」「小样本学习」。本轮不推倒 CHUNK-SERVO 的「30 步规划 + 5 步伺服」，而是补它最大的隐藏假设：**目标是由任务 ID 给定的，而且受器几何在测试时不变。**
>
> 轮次口径：会话提示的「第 1 轮」按新会话计数，不重置研究线；本文件按同一研究线计为第 13 轮，基线是第 12 轮 CHUNK-SERVO。

## 0. 先给结论：CHUNK-SERVO 缺的不是控制，是「目标是谁」

第 12 轮把瓶颈定位为「最后 3 厘米的开环执行」，这只说对了一半。最后 3 厘米之所以难，除了 chunk 内不看新图，还因为：

1. **指称失败**：指令说「左边那个蓝色杯子」，场景里有两个杯子、一个杯架；VLA 抓对了类别，抓错了实例，或者把杯架当成了杯子。目标位姿再准，也是在错误的物体上闭环。
2. **未见物品失败**：测试集的「未见物品」不是新任务，而是同一任务里的新外观/新材质/新形状。相对目标 `T_target_ee*` 假设受器几何已知；新受器一来，检索到的相对位姿就有系统偏差。
3. **标定失败**：腕部相机没有内参。第 12 轮说「一次性标定」，但没有回答「用多少张图、误差多大、误差大了怎么退」。标定失败时，IBVS 的交互矩阵 `L_s` 直接错，伺服会把目标推得更偏。

所以本轮的一句话是：

> **CHUNK-SERVO 让机器人看得更快；GAZEL 让机器人先确认「你说的是哪一个」，再决定「往哪儿闭环」。**

GAZEL 不新增学习模型。它做三件确定性的事：

- **编译**：把自由指令解析成 `(动词, 主题, 受器, 属性集, 空间约束)` 的任务帧；
- **绑定**：用 33k 演示里的 K 个参考裁剪做原型/闭式读板，把主题和受器绑到当前帧的具体区域；
- **验证**：用 Gazebo 生成 N-way K-shot 的「同场景、换指令、换外观」基准，测绑定是否真的跟着语言走，而不是跟着场景先验走。

## 1. 直觉：三个词不是三个模块，而是「编译—绑定—验证」的一条链

三个灵感词的第一反应，恰好都是**在线再堆一个模型**：

| 灵感词 | 最诱人的做法 | 为什么在 UniBot 是陷阱 | 本轮的合规实现 |
|---|---|---|---|
| **Gazebo** | 在 Gazebo 里训一个 sim-to-real 策略 | 单模型规则；sim gap；算力不划算 | Gazebo 只做**语义风洞 + 标定仪器**，不训策略 |
| **指令泛化** | 在线跑 LLM/VLM 解析、改写、生成子任务 | 第二个学习模型；延迟；不可复现；可能改错名词 | **确定性语法 + 同义词本体**，零训练，约 1ms |
| **小样本学习** | 在线 meta-learning / 微调一个接地器 | 测试时无标签；不能梯度更新；第二个模型 | **检索式 k-shot**：K 个参考裁剪 → 原型/闭式岭回归读板 |

关键在于：**把「指令泛化」从“模型要见过所有说法”变成“编译器 + 属性组合”**。32 个任务模板是语法，160 条复述是词典，33k 演示是支持库；测试时的新说法只要能解析成已知的角色槽，就不需要模型见过它。未见物体只要能拆成已知属性（颜色、形状、材质、大小、空间关系），就能用 k-shot 原型去匹配；拆不出的属性，明确回退。

## 2. 第 12 轮留下的三个隐藏假设

### 2.1 假设一：目标 = 任务 ID

CHUNK-SERVO 的检索是 `index.filter(task=task_id, phase=phase_id)`。这等于假设：测试指令一定能映射到 32 个任务 ID 之一，且同一任务的所有试次共享同一个目标。这个假设在「位置泛化」下勉强成立（受器移动但身份不变），在「干扰物」和「未见物品」下不成立：场景里可能有两个同类物体，指令的形容词才是区分它们的唯一信息。

### 2.2 假设二：受器 = 已知几何

`T_target_ee* = T_base_target^{-1} · T_base_ee` 是从演示里检索的相对位姿。它默认受器的局部几何（杯架开口、网口尺寸、试管架孔距）与演示一致。未见物品轴换的正是这个几何。相对位姿检索可以抗位置变化，但不能抗**几何变化**；几何一变，最后 3 厘米的插入轴就错了。

### 2.3 假设三：标定 = 一次性离线

腕部相机没有内参。第 12 轮的 G0 说「重投影 ≤5px」，但没有说标定失败时的降级路径。如果标定误差 10px，IBVS 的 `L_s` 误差会直接进入控制律；在接触段，这等价于用错误的雅可比做闭环。需要一个**可验证、可回退、只用少量图**的标定流程。

## 3. 三个灵感词怎么落到方案里

| 灵感词 | 落到哪里 | 具体机制 | 不做什么 |
|---|---|---|---|
| **Gazebo** | N-way K-shot 语义风洞 + 腕部标定仪器 | 用 `gz-sim` + G1 URDF 生成带真值 mask/位姿的桌面场景；控制物体外观、干扰物、背景、光照；测 top-1、mask IoU、指令交换一致性 | 不在 Gazebo 里训 VLA；不假设 Gazebo 成功率能预测真机 |
| **指令泛化** | 确定性编译器 | 语法 + 同义词本体 + 32 任务模板；输出 `(v, θ, γ, A, C)`；解析失败回退原句 | 不引入在线 LLM；不做开放式语言理解 |
| **小样本学习** | FS-Ground + FS-Calib | 从演示库取 K 个参考裁剪做原型/闭式读板；用 M 张标定图做 PnP；支持集 K=1/3/5 可扫 | 不做在线梯度更新；不训第二个深度模型 |

## 4. 形式化：把「指令泛化」写成 N-way K-shot entity linking

### 4.1 任务帧

给定指令 `ℓ`，编译器输出：

```math
F = (v, \theta, \gamma, A, C, \rho),
```

其中 `v` 是规范动词（pick/place/insert/hang/stack/fold/zip/unlock/pour/organize），`θ` 是主题物体类型，`γ` 是受器/目标类型，`A = {a_1, ..., a_m}` 是属性集（颜色、材质、形状、大小、状态），`C` 是空间/时序约束（左/右/内/上/旁），`ρ` 是原始名词短语（用于审计）。解析失败输出 `⊥`。

### 4.2 属性条件下的实体链接

给定当前观测 `O_t`（四路 RGB + 本体），候选区域集合 `R_t = {r_1, ..., r_n}`（由双目深度、桌面平面、颜色反投影、连通域生成），支持库：

```math
B = \{(\phi(x_i), a_i, \pi_i)\}_{i=1}^{N_B},
```

其中 `φ` 是冻结描述子（HSV 直方图 + Hu 矩 + LBP + 尺度，或同一 VLA checkpoint 的视觉 token），`a_i` 是属性标签，`π_i` 是演示中的相对位姿先验。

对每个槽 `s ∈ {θ, γ}`，取 `K` 个参考：

```math
S_s = \mathrm{TopK}_{i \in B}\ \mathrm{sim}(\phi(x_i), q_s),
```

`q_s` 是由指令槽 + 当前场景构造的查询。原型读板：

```math
\mu_s = \frac{1}{K}\sum_{i \in S_s}\phi(x_i),\qquad
s_s(r) = \cos(\phi(r), \mu_s).
```

闭式岭回归读板（可选，K≥3）：

```math
w_s = (X_s^\top X_s + \lambda I)^{-1} X_s^\top y_s,\qquad
s_s(r) = w_s^\top \phi(r).
```

多属性组合：

```math
\mathrm{score}(r, s) = \sum_{a \in A_s} \alpha_a\, s_a(r)
        + \beta\, s_{\mathrm{spatial}}(r, C)
        + \eta\, s_{\mathrm{VLA}}(r, s),
```

其中 `s_VLA` 是同一 checkpoint 的跨注意力显著性（C3 合规模式，可选）。最终：

```math
r_s^* = \arg\max_{r \in R_t} s(r, s),\qquad
u_s = \frac{s_{(1)} - s_{(2)}}{|s_{(1)}| + \epsilon}.
```

`u_s` 是绑定置信度；低于 `θ_g/2` 回退 VLA 开环，处于 `[θ_g/2, θ_g)` 时只用绑定做 ROI 选择、目标位姿仍用任务级检索。

### 4.3 Gazebo 的 N-way K-shot 基准

每个 episode 采样 `N` 个物体类别（含属性变体），每类给 `K` 张参考图；查询场景里放这 `N` 个物体 + 干扰物，指令只指其中一个。真值来自 Gazebo 的物体 mask/位姿。指标：

- **top-1 绑定准确率**：选中的区域是否与指令指的真实例一致；
- **mask IoU**：绑定区域与真值 mask 的重合；
- **指令交换一致性（ISC）**：同一场景、两条指不同物体的指令，绑定是否跟着换；
- **复述一致性（PC）**：同一目标、不同说法，绑定是否保持不变；
- **属性组合泛化**：训练支持库里没有的属性组合（如「半透明 + 蓝色」）能否正确绑定；
- **标定重投影误差**：FS-Calib 在加噪图像上的误差。

### 4.4 为什么这是“小样本”而不是“又一个模型”

`S_s` 是检索出来的 K 个参考，不是训练集；原型/岭回归是闭式解，在线只做点积；`λ` 和 `θ_g` 是离线校准的超参数，不是网络权重。整个流程没有反向传播、没有新参数、没有第二个 checkpoint。它更像“用演示做模板匹配”，而不是“再训一个分类器”。

## 5. 算法：GAZEL 的三个组件

### 5.1 编译器（deterministic parser）

```text
输入: ℓ (string), 本体 Ω, 任务模板 T32
输出: F 或 ⊥

1. 分词、词形还原、中英统一
2. 动词匹配: V 词典 + 同义词映射
3. 名词短语切分: 主题 NP / 受器 NP
4. 属性抽取: 颜色/材质/形状/大小/状态
5. 空间约束抽取: 左/右/内/上/旁/前/后
6. 模板检索: 与 T32 做 token overlap + 角色一致性
7. 若 verb/theme/goal 缺一 → ⊥
8. 输出 F + 解析置信度
```

### 5.2 绑定器（FS-Ground）

```text
输入: O_t, F, B, K, θ_g
输出: (r_θ*, r_γ*, T_base_target, u)

1. 在 120×160 低分辨率上做颜色反投影 + 深度不连续 + 连通域 → R_t
2. 对每个槽 s:
   a. 构造查询 q_s = 属性词 + 任务/相位先验
   b. 从 B 检索 TopK 参考（同一任务/相位优先）
   c. 计算原型 μ_s / 闭式 w_s
   d. 对每个 r ∈ R_t 打分 s(r, s)
   e. r_s* = argmax, u_s = margin
3. 若 min(u) < θ_g/2 → 回退
   若 θ_g/2 ≤ min(u) < θ_g → 只用绑定选 ROI，目标位姿用任务级
   若 min(u) ≥ θ_g → 全用绑定
4. 用头双目深度 + 桌面平面拟合 T_base_target
5. 返回 r_θ*, r_γ*, T_base_target, min(u_θ, u_γ)
```

### 5.3 标定器（FS-Calib）

```text
输入: M 张腕部图 + 已知标定板/夹爪几何 + 机器人正运动学
输出: 腕部内参 K_w, 外参 T_ee_cam, 重投影误差 e_r

1. 角点/指尖检测
2. 对每张图做 DLT / PnP
3. 联合优化 K_w, T_ee_cam（Levenberg–Marquardt）
4. 若 e_r > 5px 或 M < 4 → 失败，回退头双目 PBVS
5. 若成功 → 写入每端口配置，运行期只读
```

### 5.4 与 CHUNK-SERVO 的接口

- 编译器每个 episode 只跑一次（指令不变）；绑定器每个 5 步块跑一次（场景会动）；标定器每个端口启动时跑一次。
- `r_γ*` 和 `T_base_target` 直接替换 CHUNK-SERVO 的 `T_base_target(t)`；
- `r_θ*` 用于选择抓取点、夹爪开口和接近方向；
- 绑定置信度低时，整段回退到 CHUNK-SERVO 的任务级检索；
- 伺服、30/5 双频、编辑恢复、竞赛组合全部保留。

## 6. 与第 10–12 轮的关系：保留、升级、剪枝

**保留**：

- FACT-VLA 的相位化 BC、CAC 柔顺执行、EGP 证据门控；
- GEO-RESIDUAL 的动作条件化残差、米制表面距离、编辑检测；
- CHUNK-SERVO 的 30 步规划 + 5 步伺服、相对目标、数字孪生、单任务通道、竞赛组合。

**升级**：

- 任务级检索 → **指令级角色槽 + 实例绑定**；
- 一次性标定 → **k-shot 可验证标定 + 显式回退**；
- Gazebo 只做控制标定 → **同时做 N-way K-shot 语义风洞**；
- 相对目标只抗位置 → **属性组合抗外观/材质/形状变化**；
- 单一置信度门 → **解析置信度 + 绑定置信度 + 标定置信度三级门**。

**剪枝**：

- 不做在线 LLM/VLM 解析器（第二个模型）；
- 不做端到端指令增强重训（算力/收益不划算）；
- 不做全 32 任务高保真 Gazebo 孪生（材质/透明/布料/人扰保真度低）；
- 不做在线 meta-learning / 梯度更新（测试时无标签、延迟高、合规风险）；
- 不做 6D 物体位姿网络（透明/反光不可靠，且是第二个模型）；
- 不做“为每个任务写一个 parser”（32 个模板共享同一套语法，避免过拟合）。

## 7. 实验门 G8–G13

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G8 | 编译器是否覆盖官方复述？ | 32 模板 × 16 条（1 canonical + 5 官方 + 10 规则）= 512；槽 F1 ≥0.90；解析失败 ≤10% | 退回任务 ID 检索；只把 parser 当审计工具 |
| G9 | k-shot 绑定是否可信？ | Gazebo N-way K=5 top-1 ≥80%；mask IoU ≥0.70；属性组合 ≥65% | 增大 K；加入 VLA 显著性；否则只做任务级 |
| G10 | 指令交换/复述是否真的改变/保持绑定？ | ISC ≥0.75；PC ≥0.80；同场景换指令时绑定区域显著变化 | 说明绑定被场景先验主导；停止上线 |
| G11 | 腕部 k-shot 标定是否可用？ | 重投影 ≤5px；M≤5；失败可检测 | 只用头双目 PBVS；腕部只做 2D 粗对齐 |
| G12 | 真机单任务是否涨点？ | 5 任务 A/B 中 ≥3 个 +10pp；FoldTowel 不回归 | 不提交 GAZEL 版本；保留 parser 诊断 |
| G13 | 端到端延迟是否可接受？ | 绑定+解析 p99 ≤10ms；总 p99 ≤150ms | 降分辨率/跳帧/关绑定 |

**预注册的 kill criteria**：如果 G9 的属性组合泛化 <50%，说明支持库无法表达测试属性，GAZEL 的绑定层应整体砍掉，只保留 parser 和 FS-Calib；如果 G10 的 ISC <0.6 或 PC <0.7，说明当前 VLA/场景先验压过了语言（或绑定对说法过敏），绑定层没有意义。

## 8. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 属性词表覆盖不了未见物体 | 绑定到错误实例 | 组合属性测试；置信度门；回退任务级 |
| Gazebo 渲染与真机材质差距 | 风洞指标虚高 | 只在 Gazebo 做相对排序；真机 A/B 校准；不报绝对成功率 |
| 手写描述子太弱 | 透明/反光/线缆失败 | 用深度/轮廓；可选同 checkpoint 视觉 token；失败回退 |
| 闭式读板被判定为第二个模型 | 合规风险 | 优先纯原型（无拟合）；岭回归仅离线校准；文档写清 |
| parser 过拟合 32 模板 | 换说法就失败 | 160 条复述 + 同义词本体；G8 门；失败回退原句 |
| 标定板不在测试场景 | FS-Calib 无法执行 | 用夹爪几何 + 正运动学；或头双目手眼标定 |
| 绑定延迟挤占伺服预算 | 总延迟上升 | 低分辨率候选生成；每 5 步一次而非每帧；p99 门 |
| 两个相似实例 | 绑定漂移 | K-shot 参考 + 空间约束 + 指令交换测试 |
| 评测指令其实是固定的 | 收益被高估 | 明确声明：主要收益来自未见物品/干扰物，不是复述 |
| 支持库标签噪声 | 原型偏移 | 用 EE 轨迹自动选关键帧；小规模人工校验；鲁棒中位数原型 |

## 9. 一句话押注

**用确定性编译器把指令拆成角色槽，用 33k 演示的 K 个参考做原型绑定，用 Gazebo 的 N-way K-shot 风洞验证“绑定是否跟着语言走”，再把绑定结果接到 CHUNK-SERVO 的相对目标上——在不新增学习模型的前提下，把“最后 3 厘米”从“对哪个任务闭环”推进到“对哪个实例闭环”。**

## 10. 当前方案最大的风险

**属性词表与支持库覆盖不了测试时的未见物体；组合属性一旦无法分解，绑定层会静默回退，GAZEL 的预期收益随之消失。**

# 第 13 轮产物 · GAZEL 技术报告

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「GAZEL」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是把 CHUNK-SERVO 的「目标检索」从任务级推进到**指令级实例绑定**。轮次口径：会话提示的「第 1 轮」按新会话计数，不重置研究线；本报告按同一研究线计为第 13 轮。

## 0. 结论与边界

### 0.1 一句话结论

CHUNK-SERVO 的 30 步规划 + 5 步伺服解决的是「怎么闭环」，但没有回答「对哪个实例闭环」。GAZEL 用确定性编译器把指令拆成角色槽，用 33k 演示中的 K 个参考裁剪做原型/闭式读板，把主题和受器绑到当前帧的具体区域，再用 Gazebo 的 N-way K-shot 风洞验证「绑定是否跟着语言走」；绑定结果直接替换 CHUNK-SERVO 的相对目标，置信度低则回退原任务级检索。全程只保留一个学习模型（官方 WLA/VLA），不新增第二个 checkpoint。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、排行榜 JSON 直接核实 | 32 任务 / 10 次 / 5 轴 / 单模型；四路 RGB、无深度/力/触觉；33,276 eps；WLA `chunk_size=30` |
| B | 我们在公开数据/网页/代码上做的分析，可复现 | 头双目基线 58.2526 mm、焦距约 282 px；立体深度误差推导；CHUNK-SERVO 的 5 步反馈周期 |
| C | 设计假设，需 G8–G13 验证 | k-shot 绑定 top-1 ≥80%；属性组合泛化 ≥65%；真机 +10pp |
| D | 公开但尚未逐条复核的线索 | Gazebo 渲染与真机材质的对应关系；官方 instruction 是否固定 |

### 0.3 本轮不做什么

- 不在线跑 LLM/VLM 解析器、GroundingDINO、SAM2；不引入第二个学习模型。
- 不做在线 meta-learning / 梯度更新；FS-Ground 的“学习”是离线闭式解或纯原型。
- 不在 Gazebo 里训练 VLA，也不把 Gazebo 成功率当真实成功率。
- 不做全 32 任务高保真孪生；只做 8 个代表任务的**语义/视觉**风洞。
- 不做 6D 物体位姿网络；透明/反光/线缆仍走置信度门 + 回退。
- 不把「指令泛化」偷换成「开放式语言理解」；只做 32 任务模板覆盖的封闭域编译。
- 不假设官方测试指令一定会改写；主要收益来自未见物品/干扰物轴的实例绑定。

## 1. 问题形式化

### 1.1 观测与动作接口

沿用第 12 轮的接口事实：

- 观测：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB 480×640；双臂关节、EE 位姿（base 系 xyz+rpy）、夹爪、下身体、语言字符串。
- 动作：`ee` 模式下为左右 EE 绝对目标位姿 + 夹爪 + 7 维 pivot；`action_chunk_size` 固定，chunk 内无新观测。
- 没有 depth、camera_info、force/torque、tactile。
- 评测跨 N 台机器人，端口 8765 起连续，每端口独立 `reset()`。

记一次 episode 的观测序列为 `O_{0:T} = {(I_t^1, ..., I_t^4, q_t, x_t^{ee}, g_t, \ell)}_{t=0}^{T}`，其中 `\ell` 在 episode 内恒定。

### 1.2 任务帧与语法

定义规范符号集：

- 动词 `V = {pick, place, insert, hang, stack, fold, zip, unlock, pour, organize, ...}`；
- 主题物体类型 `O`；
- 受器/目标类型 `G`；
- 属性 `A = {color, material, shape, size, state}`，每个属性有有限取值；
- 空间约束 `C = {left, right, inside, on, next_to, front, back, ...}`。

任务帧：

```math
F = (v, \theta, \gamma, A_\theta, A_\gamma, C, \rho),
```

其中 `v ∈ V`，`θ ∈ O`，`γ ∈ G`，`A_θ, A_\gamma` 分别是主题/受器的属性集，`C` 是空间约束，`ρ` 是原始名词短语（审计用）。

编译器 `κ`：

```math
\kappa: \mathcal L \to \mathcal F \cup \{\bot\}.
```

`⊥` 表示解析失败。`κ` 由语法 `G`、同义词本体 `Ω`、32 任务模板 `T_{32}` 三部分组成；不含学习参数。

### 1.3 属性条件下的实体链接

当前帧的候选区域：

```math
R_t = \{r_1, ..., r_n\},
```

每个 `r_i` 是一个连通区域（mask + 双目深度 + 桌面平面支撑）。支持库：

```math
\mathcal B = \{(\phi(x_i), a_i, \pi_i)\}_{i=1}^{N_B},
```

`φ` 是冻结描述子，`a_i` 是属性标签，`π_i` 是演示关键帧中的相对位姿先验。

对槽 `s ∈ {θ, γ}`，构造查询 `q_s`（属性词 + 任务/相位先验 + 当前场景上下文），检索：

```math
S_s = \operatorname{TopK}_{i \in \mathcal B}\ \operatorname{sim}(\phi(x_i), q_s).
```

原型读板：

```math
\mu_s = \frac{1}{K}\sum_{i \in S_s}\phi(x_i),\qquad
s_s(r) = \cos(\phi(r), \mu_s).
```

闭式岭回归读板（K≥3，可选）：

```math
w_s = (X_s^\top X_s + \lambda I)^{-1} X_s^\top y_s,\qquad
s_s(r) = w_s^\top \phi(r).
```

其中 `X_s ∈ R^{K×d}` 是支持特征，`y_s ∈ {0,1}^K` 是属性/实例标签，`λ` 由离线交叉验证选定。若岭回归使用**固定的属性支持集**（离线按属性分组，而非查询时检索的 top-K），`w_s` 可离线预计算，在线只做 `O(nd)` 点积；若使用查询时检索的 `S_s`，则在线解 `d×d` 线性方程，`d≤256` 时约 1ms。

多属性组合：

```math
\mathrm{score}(r, s) = \sum_{a \in A_s} \alpha_a\, s_a(r)
        + \beta\, s_{\mathrm{spatial}}(r, C)
        + \eta\, s_{\mathrm{VLA}}(r, s),
```

`α_a` 是属性权重（先验：颜色/形状高，材质中，状态低）；`s_spatial` 是空间约束满足度；`s_VLA` 是同一 checkpoint 的跨注意力显著性（C3 合规模式，可选，默认关闭）。

最终选择与置信度：

```math
r_s^* = \arg\max_{r \in R_t} s(r, s),\qquad
u_s = \frac{s_{(1)} - s_{(2)}}{|s_{(1)}| + \epsilon}.
```

`u_s` 是 top-1 与 top-2 的归一化 margin；低于 `θ_g` 回退。

### 1.4 目标位姿与执行

给定绑定的受器区域 `r_γ*`，用头双目深度 + 桌面平面 + 局部点云拟合得到：

```math
T_{\mathrm{base},\gamma}(t) \in SE(3).
```

从支持库中选与 `r_γ*` 的属性/几何最匹配的关键帧，取相对目标 `T_{\gamma,ee}^*`，期望夹爪位姿：

```math
T_{\mathrm{base},ee}^d(t) = T_{\mathrm{base},\gamma}(t)\,T_{\gamma,ee}^*.
```

之后完全复用 CHUNK-SERVO：

```math
a_{cmd} = a_{ff}\circ \exp(\Delta),\qquad
\Delta = \operatorname{clip}(K_p e + K_d \dot e, \pm\delta_p, \pm\delta_r),
```

```math
e = \log\left(T_{\mathrm{base},ee}(t)^{-1} T_{\mathrm{base},ee}^d(t)\right).
```

### 1.5 优化目标与安全约束

总分仍是：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j}.
```

GAZEL 的目标不是直接最大化 `S`，而是在**不劣于基线**的约束下，提高未见物品/干扰物轴的 `p_t`：

```math
\max_{\kappa, \mathcal B, \theta_g}\ \mathbb E[S]
\quad \text{s.t.}\quad
\mathbb E[S] \ge \mathbb E[S_{\mathrm{CHUNK\text{-}SERVO}}],
```

约束通过安全门实现，见 §5.3。

- 编译器每个 episode 只跑一次；绑定器每个 5 步块跑一次；标定器每个端口启动时跑一次。
- 所有新组件都是 CPU 确定性代码，不抢 GPU；VLA 仍是唯一学习模型。

### 2.2 离线管线

```text
A. 本体与模板
   1. 从 32 个任务 canonical 描述 + 160 条复述抽取动词/名词/属性/空间词
   2. 人工审校同义词本体 Ω（每类只允许同物映射，不允许 sibling 替换）
   3. 生成 32 个任务模板 T32（verb/theme/goal/attribute slots）

B. 演示支持库
   1. 对每个 episode 做相位分割（FACT-VLA CPT / GEO-RESIDUAL）
   2. 用 EE 轨迹 + 夹爪开合 + 接触信号选关键帧
   3. 在关键帧上裁出主题/受器 ROI（头双目 + 腕部）
   4. 计算描述子 φ（HSV/Hu/LBP/尺度；可选 VLA token）
   5. 存 (task, phase, slot, φ, crop, T_target_ee, quality)
   6. 用 200–500 个人工校验样本估计标签噪声

C. Gazebo 风洞
   1. G1 URDF + 桌面场景 + 四路相机
   2. 8 个代表任务族：挂/插/叠/拉链/锁/倒/装/整理
   3. 生成 N-way K-shot episode：N=5, K∈{1,5}, Q=20
   4. 生成指令变体：canonical / 复述 / 属性替换 / 物体替换
   5. 生成场景变体：颜色/材质/形状/干扰物/背景/光照/遮挡
   6. 记录真值 mask、位姿、指令槽
   7. 用 §6 的指标校准 θ_g、α_a、K、λ
```

### 2.3 在线管线

```text
t=0 (reset):
  1. κ(ℓ) → F 或 ⊥
  2. 若 F=⊥: 直接用原句 + 任务级检索（CHUNK-SERVO 回退）
  3. FS-Calib 读取本端口标定（启动时已完成）
  4. 初始化 support_cache: 对 θ/γ 各检索 TopK 参考

每个 5 步块:
  1. 候选区域 R_t（低分辨率颜色反投影 + 深度 + 连通域）
  2. FS-Ground: 对 θ/γ 打分，得到 r_θ*, r_γ*, u
  3. 若 min(u) < θ_g: 回退任务级目标
  4. 否则: 估计 T_base_target, 选 T_target_ee*
  5. VLA plan 切片 + 伺服修正
  6. 返回 5 步 chunk
  7. 若 edit_score > θ_e: 清空 grounding_cache，下一块重绑
```

### 2.4 状态机

```text
INIT ──κ(ℓ)──▶ COMPILED ──first obs──▶ GROUND
  │                 │                     │
  │                 └─⊥──▶ FALLBACK ──────┤
  │                                       ├─ u ≥ θ_g ──▶ SERVO
  │                                       └─ u < θ_g ──▶ FALLBACK
  │
  └──────────────────────────────────────────────────────▶ DONE
GROUND ──edit_score > θ_e──▶ REGROUND ──▶ GROUND
SERVO  ──d_t < d_c──▶ CONTACT ──released──▶ SERVO
任意状态 ──success / max steps──▶ DONE
```

- `COMPILED`：任务帧就绪，支持库已分片。
- `GROUND`：每个 5 步块做一次实例绑定。
- `SERVO`：CHUNK-SERVO 的 PBVS/IBVS 混合。
- `CONTACT`：法向缩幅、切向保留。
- `REGROUND`：编辑检测触发，清空缓存，下一块重绑。
- `FALLBACK`：任务级检索或 VLA 开环。

## 3. 算法

### 3.1 编译器：确定性语法 + 同义词本体

#### 3.1.1 语法

用扩展巴科斯范式表示（简化）：

```text
Instruction  ::= Action Phrase (Prep Phrase)?
Action       ::= Verb
Phrase       ::= NP
NP           ::= (Attr)* Noun
Attr         ::= Color | Material | Shape | Size | State | Spatial
Prep Phrase  ::= Prep NP
```

主题 NP 与受器 NP 的角色由动词的格框架决定：

- `pick/place/insert/hang/stack/pour`：主题 = 直接宾语，受器 = 介词宾语；
- `fold/zip/unlock/organize`：主题 = 直接宾语，受器可省略；
- 若动词有歧义，用 32 任务模板做角色消歧。

#### 3.1.2 同义词本体

`Ω` 是人工审校的映射表：

- 同物映射：`mug → cup`、`cellphone → phone`、`charger plug → charger`；
- **禁止 sibling 替换**：`plate ↛ dish`、`cup ↛ bottle`、`bowl ↛ plate`；
- 属性同义：`crimson → red`、`azure → blue`；`transparent`/`translucent` 归入 `transparency` 属性，但保留原词作为子标签，不做完全合并；
- 空间同义：`beside → next_to`、`within → inside`。

本体是**封闭域**：只覆盖 32 任务及其复述；域外词直接让 `κ` 输出 `⊥`，不做开放式猜测。

#### 3.1.3 解析置信度

```math
u_{\mathrm{parse}} = w_v \mathbb 1[v \in V] + w_\theta \mathbb 1[\theta \in O] + w_\gamma \mathbb 1[\gamma \in G] + w_T \operatorname{sim}(F, T_{32}).
```

任一项缺失或 `u_parse < θ_p` → `⊥`。

#### 3.1.4 复杂度

分词 O(|ℓ|)，词典匹配 O(|ℓ|)，模板检索 O(|T32|)，总体 O(|ℓ| + |Ω| + 32)。Python 实现约 0.5–2ms。

### 3.2 FS-Ground：k-shot 原型/闭式读板

#### 3.2.1 候选区域生成

在 120×160 低分辨率上：

1. **颜色反投影**：对属性颜色做 HSV 直方图反投影；
2. **深度不连续**：头双目 SGBM 视差 → 深度；剔除背景平面；
3. **桌面平面**：RANSAC 拟合桌面，保留平面上方 0–30cm 的点；
4. **连通域**：形态学开闭 + 连通域，面积/长宽比过滤；
5. **排序**：按“属性匹配 + 深度有效性 + 距离夹爪”排序，保留 top-`n`（n≤100）。

#### 3.2.2 支持集检索

```text
输入: 槽 s, 属性集 A_s, 任务/相位, 当前场景 q_s
1. 硬过滤: task, phase, slot（避免跨任务污染）
2. 属性过滤: 颜色/形状必须匹配；材质缺失时放宽
3. 描述子检索: sim(φ(x_i), q_s) top-50
4. 多样性重排: MMR(q_s, S) 选 K 个
5. 若 |S_s| < K: 用同任务/同相位的最近邻补齐
```

MMR：

```math
\mathrm{MMR}(i) = \lambda_{\mathrm{mmr}}\operatorname{sim}(\phi(x_i), q_s)
               - (1-\lambda_{\mathrm{mmr}})\max_{j \in S}\operatorname{sim}(\phi(x_i), \phi(x_j)).
```

`λ_mmr` 默认 0.7；避免 K 个参考全是同一帧的相邻帧。

#### 3.2.3 读板

- **K=1**：最近邻，`s_s(r) = cos(φ(r), φ(x_1))`。
- **K≥3**：原型，`μ_s = mean`；若支持集有明显离群，改用几何中位数。
- **K≥3 且标签可用**：闭式岭回归；`λ` 由离线留一法选。
- **属性组合**：对每个属性单独算 `s_a`，再加权；未见组合不会“平均”成一个原型，而是各属性各自打分。

#### 3.2.4 置信度与回退

```math
u_s = \frac{s_{(1)} - s_{(2)}}{|s_{(1)}| + \epsilon}.
```

- `u_s ≥ θ_g`：使用绑定；
- `θ_g/2 ≤ u_s < θ_g`：只用绑定做 ROI 选择，目标位姿仍用任务级检索；
- `u_s < θ_g/2`：完全回退。

三级门比二值门更稳，尤其对透明/反光/遮挡。

### 3.3 FS-Calib：k-shot 腕部标定

#### 3.3.1 问题

腕部相机没有内参矩阵。需要估计：

```math
K_w = \begin{bmatrix} f_x & 0 & c_x \\ 0 & f_y & c_y \\ 0 & 0 & 1 \end{bmatrix},\qquad
T_{ee,cam} \in SE(3).
```

#### 3.3.2 方案 A：标定板

用 ChArUco 板，腕部相机在 M 个不同位姿拍摄：

```math
\min_{K_w, T_{ee,cam}} \sum_{m=1}^{M}\sum_{j=1}^{N_p}
\left\|\pi\left(K_w,\ T_{base,ee}^{(m)}\,T_{ee,cam},\ X_j\right) - u_{m,j}\right\|^2,
```

其中 `X_j` 是标定板角点在 base 系的三维坐标（板位姿已知），`N_p` 是每张图的角点数。

- 先用 DLT 求初值；
- 再用 Levenberg–Marquardt 联合优化；
- M≥4 且标定板非共面 → 可观测；
- 重投影误差 ≤5px 通过。

#### 3.3.3 方案 B：夹爪几何 + 手眼标定

若测试现场没有标定板：

- 用 Dex1 指尖的已知 3D 点 + 正运动学；
- 移动机械臂到 M 个位姿，腕部相机看指尖；
- 解 `AX = XB` 手眼标定；
- 至少 M=5 个非退化位姿；
- 失败则只用头双目 PBVS。

#### 3.3.4 复杂度

离线；M=5 张图，每张 N_p≈30 角点，LM 迭代 50 次；CPU 秒级。在线只读配置。

### 3.4 Gazebo N-way K-shot 语义风洞

#### 3.4.1 仿真器选择

用 **Gazebo Sim (`gz-sim`)** + `ros_gz` 桥：

- 支持 URDF/SDF、G1 URDF、四路 RGB 相机；
- 支持 headless `gz sim -s`，可并行生成；
- 物理引擎用于简单刚体摆放/遮挡，不用于接触密集的插入/拉链/布料；
- 渲染用于语义/视觉风洞，不用于宣称真机成功率。

**为什么不是 IsaacLab/MuJoCo**：第 12 轮已经用它们做控制标定；本轮需要的是**轻量、可并行、易改材质/光照/物体**的语义风洞。Gazebo 的 ROS 生态和 SDF 场景生成更适合这件事；接触物理仍交给真机/单任务通道。

#### 3.4.3 指标

```math
\mathrm{Acc}_{\mathrm{top1}} = \frac{1}{Q}\sum_{q=1}^{Q}\mathbb 1[r_q^* = r_q^{\mathrm{gt}}],
```

```math
\mathrm{IoU} = \frac{1}{Q}\sum_{q=1}^{Q}\frac{|r_q^* \cap r_q^{\mathrm{gt}}|}{|r_q^* \cup r_q^{\mathrm{gt}}|},
```

指令交换一致性：

```math
\mathrm{ISC} = \frac{1}{|\mathcal P|}\sum_{(i,j)\in\mathcal P}
\mathbb 1\left[r^*(\ell_i) \ne r^*(\ell_j)\right],
```

其中 `P` 是“同场景、两条指令指不同物体”的配对。ISC 高说明绑定跟着语言走；ISC 低说明绑定被场景先验主导。

互补指标是同一目标、不同说法的**复述一致性**：

```math
\mathrm{PC} = \frac{1}{|\mathcal R|}\sum_{(i,j)\in\mathcal R}
\mathbb 1\left[r^*(\ell_i) = r^*(\ell_j)\right],
```

`R` 是“同场景、同一目标、不同复述”的配对。ISC 测“换目标会不会换绑定”，PC 测“换说法会不会丢绑定”。两者一起看，才能区分“真的在用语言”与“只是跟着显著物体走”。

#### 3.4.4 风洞效度门

Gazebo 只用于**相对排序**，不用于绝对成功率。上线前做：

- 复用 §6.4 的 5 任务 × 5 对 A/B（共 50 次 trial），默认只测最终选定的 K；若要在 K=1/K=5 之间选，追加 5 任务 × 5 对（再 50 次），总计 100 次 trial；
- 计算 Gazebo top-1 与真机成功率的 Spearman `ρ`；
- 只有 `ρ ≥ 0.7` 才允许用 Gazebo 选 K/θ_g/α；否则只用真机。

#### 3.6.2 绑定

```python
def ground(obs, frame, bank, K=5, theta_g=0.25):
    regions = candidate_regions(obs, max_n=100)   # 120x160
    if not regions:
        return None

    goals = {}
    for slot, noun, attrs in [("theme", frame.theta, frame.A_theta),
                              ("goal", frame.gamma, frame.A_gamma)]:
        support = retrieve(bank, task=frame.task, slot=slot, attrs=attrs,
                           query=obs, K=K)
        if len(support) < K:
            support = fill_nearest(bank, frame.task, slot, support, K)
        model = fit_readout(support, attrs)       # prototype or closed-form
        scores = [model.score(r, attrs) for r in regions]
        order = argsort_desc(scores)
        best, second = order[0], order[1] if len(order) > 1 else None
        u = margin(scores[best], scores[second] if second is not None else 0.0)
        if u < theta_g / 2:
            return None
        goals[slot] = (regions[best], u, support)

    T_target = estimate_target_pose(obs, goals["goal"][0])
    T_rel = select_relative_pose(goals["goal"][2], frame)
    return Grounding(goals, T_target, T_rel,
                     confidence=min(goals[s][1] for s in goals))
```

## 4. 复杂度分析

设：

- `|ℓ|`：指令长度，典型 20–60 token；
- `|Ω|`：本体条目，约 500；
- `n`：候选区域数，≤100；
- `d`：描述子维度，64–256；
- `K`：支持集大小，1–10；
- `N_B`：支持库规模，约 20–40k；
- `N_task`：单任务支持库，约 600–1,500。

| 步骤 | 复杂度 | 典型量级 | 备注 |
|---|---|---|---|
| 编译 | O(\|ℓ\| + \|Ω\| + 32) | <2ms | 每 episode 一次 |
| 候选生成 | O(W H + n) | 120×160 ≈ 19.2k px | 低分辨率 |
| 特征 | O(n d) | 100×128 = 12.8k | 手写描述子 |
| 检索 | O(N_task d + K d) | 1.5k×128 ≈ 192k | 倒排索引 + rerank |
| 读板 | O(n d)（固定属性支持集）或 O(d³ + K d² + n d)（在线岭回归） | 12.8k / ~16M | 原型优先 |
| 打分 | O(n K d) | 100×5×128 = 64k | 多属性可并行 |
| 位姿 | O(n_roi) | ROI 点云 1–5k | 平面/ICP |
| 标定 | 离线 | 秒级 | M=5 |
| 风洞 | O(T M S Q) | 离线 | 渲染主导 |

在线总开销目标 **<10ms/5 步块**，占 167ms 执行块的 6% 以内。用 NumPy 向量化；Python 解释器开销通过批处理和缓存控制。若 p99 超 10ms，降分辨率到 96×128 或每 2 个块绑一次。

## 5. 正确性论证

### 5.1 假设

- **A1（语法封闭）**：测试指令属于 `L(G)`，或其角色槽可由 `T32` 覆盖。否则 `κ` 输出 `⊥`，走回退。
- **A2（本体同物）**：`Ω` 只做同物映射，不把 sibling 合并。由人工审校保证。
- **A3（支持覆盖）**：对每个槽和属性组合，支持库至少有一个参考，或属性可分解为已知属性的组合。
- **A4（特征可分）**：在给定属性下，正确实例与错误实例的读板分数有正 margin。
- **A5（门控可校准）**：`θ_g` 在离线/风洞数据上校准，且测试分布与校准分布同族。
- **A6（回退一致）**：`FALLBACK` 路径与 CHUNK-SERVO 基线逐动作一致。

### 5.2 引理

#### 引理 1（编译器可靠性）

若 `A1`、`A2` 成立，且语法 `G` 无歧义，则对 `ℓ ∈ L(G)`，`κ(ℓ)` 是唯一解析，且其 `v, θ, γ` 是 `ℓ` 所指的规范符号。

**证明**：由 `G` 的无歧义性，语法树唯一；由 `Ω` 的同物映射，每个词法项映射到唯一规范符号；由动词格框架，主题/受器角色唯一。归纳于推导树。∎

**边界**：若 `ℓ` 含域外词或 sibling 歧义，`κ` 返回 `⊥`，引理不适用；这正是回退的触发条件。

#### 引理 2（原型读板的泛化界，草图）

设 `φ(x) ∈ R^d`，`||φ|| ≤ B`，支持集 `S` 有 `K` 个 i.i.d. 样本，类条件分布由 margin `γ` 可分。则原型分类器的期望 0-1 风险以概率 `1-δ` 满足：

```math
R(\hat c) \le O\left(\frac{B}{\gamma}\sqrt{\frac{\log(1/\delta)}{K}}\right).
```

**证明草图**：原型与类条件均值之差由 `O(B/√K)` 的集中不等式控制；若均值间距 ≥γ，则分类错误事件包含在“原型偏离均值超过 γ/2”事件中；用 union bound 得证。更精确的界含 `√(log d)` 因子，此处只保留 K 的缩放。常数依赖特征分布，实际风险需用留出集估计。∎

**含义**：K 从 1 增到 5，界约缩小 `√5 ≈ 2.24` 倍；但这是最坏界，实际收益可能更小。K>10 后边际收益递减，且检索多样性下降。

#### 引理 3（标定可观测性）

对针孔相机，若已知 `M ≥ 4` 个非共面 3D 点及其像素对应，且相机内参为 5 参数模型（`f_x, f_y, c_x, c_y, skew=0`），则 `K_w` 与 `T_ee,cam` 在一般位姿下可观测；若点共面，存在二重歧义。

**证明**：标准 DLT/PnP 可观测性结论；共面情形的二重歧义见相机标定文献。∎

**工程含义**：FS-Calib 必须用非共面标定板或多位姿；若只有共面点，用多个机器人位姿联合求解，或用头双目手眼标定。

### 5.3 安全门定理

设：

- `G` 为门控事件（使用 GAZEL 绑定）；
- 在 `G=1` 上，`C` 为绑定正确事件，`q = P(C|G=1)`；
- `p_c = P(Y=1|G=1,C)`，`p_w = P(Y=1|G=1,¬C)`；
- 在 `G=0` 上，系统与基线逐动作一致，成功率 `p_b`。

则：

```math
P(Y=1) = P(G)\left[q p_c + (1-q)p_w\right] + (1-P(G))p_b.
```

**定理**：若

```math
q p_c + (1-q)p_w \ge p_b,
```

则 `P(Y=1) ≥ p_b`。

**证明**：代入上式，括号项 ≥ `p_b`，加权平均 ≥ `p_b`。∎

**推论（所需绑定精度）**：若 `p_c > p_w`，则充分条件为

```math
q \ge \frac{p_b - p_w}{p_c - p_w}.
```

**数值示例**（仅示意，不是实测）：

| `p_b` | `p_c` | `p_w` | 所需 `q` |
|---:|---:|---:|---:|
| 0.30 | 0.55 | 0.20 | 0.286 |
| 0.30 | 0.50 | 0.25 | 0.200 |
| 0.30 | 0.45 | 0.28 | 0.118 |
| 0.25 | 0.50 | 0.15 | 0.286 |

**解读**：只要错误绑定不至于把成功率打到 0，门控对 `q` 的要求并不苛刻。但这依赖两个未验证量：`p_c` 和 `p_w`。如果错误绑定会主动把物体推飞（`p_w≈0`），则 `q ≥ p_b/p_c`，要求高得多。因此必须**测 `p_w`**，不能假设“错了也没事”。

**边界**：定理是条件性的；它不保证 `q p_c + (1-q)p_w ≥ p_b` 在真实分布上成立。`θ_g` 必须用留出数据校准，并在单任务通道验证。

### 5.4 为什么不做“端到端学习绑定”

- 测试时无标签，在线梯度更新不可行；
- 第二个深度模型违反单模型规则；
- 32 任务数据不足以训练开放域接地器；
- 闭式/原型读板可审计、可回退、CPU 轻量；
- 若未来允许第二个模型，本方案的结构（槽 + 支持集 + 门控）仍可作为其安全外壳。

| 闭式读板被判定为第二模型 | 合规风险 | 优先纯原型；岭回归离线；文档说明 | 改用纯原型/最近邻 |

| 标定板不在现场 | FS-Calib 失败 | 夹爪几何 + 手眼；头双目兜底 | 只用 PBVS |
| 绑定延迟挤占伺服 | 总延迟上升 | 低分辨率；每 5 步；缓存 | 降频/降分辨率 |
| 两个相似实例 | 绑定漂移 | K-shot + 空间约束 + ISC 测试 | 提高 θ_g |
| 支持库标签噪声 | 原型偏移 | EE 轨迹自动选帧；人工校验；中位数原型 | 清洗/降 K |
| 评测指令固定 | 收益高估 | 明确声明主收益在未见物品/干扰物 | 只报实例绑定收益 |
| 绑定与 VLA 意图冲突 | 动作被拉向错误物体 | 安全门 + Δ 限幅 + 编辑检测 | 回退 VLA |
| 多端口共享支持库内存 | OOM | 只读共享 + copy-on-write；每端口小缓存 | 降 K/分片 |

### 9.3 失败语义

- `κ` 失败：`TaskFrame=None`，绑定器不运行，走 CHUNK-SERVO 任务级检索。
- 绑定失败：`Grounding=None`，走 CHUNK-SERVO 任务级检索。
- 标定失败：`WristCalib=None`，腕部只做 2D 归一化对齐，3D 目标用头双目。
- 任何异常：返回上一组合法 chunk 或安全 hold；绝不返回 NaN/错误形状。
- 所有回退路径逐动作与基线一致（A6），保证安全门定理成立。

## 11. 一句话押注

**用确定性编译器把指令拆成角色槽，用 33k 演示的 K 个参考做原型绑定，用 Gazebo 的 N-way K-shot 风洞验证“绑定是否跟着语言走”，再把绑定结果接到 CHUNK-SERVO 的相对目标上——在不新增学习模型的前提下，把“最后 3 厘米”从“对哪个任务闭环”推进到“对哪个实例闭环”。**

## 12. 当前方案最大的风险

**属性词表与支持库覆盖不了测试时的未见物体；组合属性一旦无法分解，绑定层会静默回退，GAZEL 的预期收益随之消失。**
