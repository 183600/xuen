# 想法区 · 从 X-DUB/EC* 到 X-DUB/IP*

**灵感词**：fault-tolerant algorithm / 整数规划 / backtracking  
**起点**：v0.7「X-DUB/EC*」。它已经把"精确判定"做成了证书：逐节点能量界 `E(R,A)`、截止期界、阈值 memo、`EC-SOLVE`。本轮不推翻它；本轮补的是它自己指出的那个缺口——**分区型实例上 `E` 恒等于 `H`，精确判定退化成纯枚举**。

## 一句话直觉：最后一格不是"能量不够大"，而是"能量是体积，容量是整数"

v0.7 的

```text
E(R,A) = ceil( (Σ_{i∈R} p_i + Σ_k A_k) / m )
```

是一个**体积界**。它在 pool30 上很有效，但在分区型实例上有一个致命性质：当总工时恰好填满 `m` 台机器的容量时，`E=H` 在**每一个节点**都取等号，能量剪枝恒不触发。v0.7 的 DEC 于是退化成"枚举所有赋值"。

这一轮我不再问"怎么把能量界再加强一点"，而是问：**在 `E=H` 却不可行的实例里，到底缺了哪条信息？**

缺的是**不可分割性**。两个最小反例：

1. `p=(6,6,6), m=2, H=11`：`E=ceil(18/2)=9≤11`，但两台机器中总有一台要放两个 6，`12>11`。`OPT=12`，`E` 比 `OPT` 低 3。
2. `p=(4,4,4,4,4,4,4), m=3, H=10`：`E=ceil(28/3)=10=H`，能量界**恰好紧**，但每台机器最多放两个 4（三个 4 是 12），三台最多 6 个，装不下 7 个。`OPT=12`。

第二个反例是这一轮的起点：它说明 **`E=H` 不等于可行性**。`E` 是容量多面体的 LP/体积松弛；真正的容量约束是"整数分箱"。

## 于是本轮的动作：把容量多面体的整数包络解出来，作为第二个可采纳下界

定义**赋值松弛** `PACK(σ,H)`：只问"能否把 `R` 中的任务分到 `m` 台机器，使机器 `k` 的负载不超过 `H-A_k`，且每个任务 `i` 在自己的窗口 `[max(A_k,est_i), H-q_i]` 内放得下 `p_i`"。它丢掉优先约束和 sequencing，但保留**整数性**与**每台机器的容量**。

```text
PACK(σ,H) = ∃ α:R→[m]:
    ∀k:  Σ_{i:α(i)=k} p_i ≤ H - A_k
    ∀i:  max(A_{α(i)}, est_i) + p_i + q_i ≤ H
```

`L_PACK(σ)=min{H: PACK(σ,H)}`。它是可采纳的（任一可行调度诱导一个赋值），并且在分区型实例上可以远高于 `L0`。m=2 时它是 subset-sum，用 bitset 在 `O(nH/word)` 内精确解；m≥3 时是 bin packing，用带回溯的 B&B（n≤13）精确解。

这样下界层次变成：

```text
L0(σ) = max(C, max_i(est_i+p_i+q_i), ceil(Σp/m))
L_IP(σ) = max( L0, L_DFF, L_PACK )
L0 ≤ L_IP ≤ OPT
```

其中 `L_DFF` 是一个便宜的调和 dual-feasible-function 界：对任意 `t≥1`，

```text
L_DFF = max_t  t · ceil( Σ_{i∈R} floor(p_i/t) / m ).
```

它比 `L_PACK` 弱，但 `O(n·pmax)`，是 PACK 超时时的降级证书。

## 为什么叫 fault-tolerant：因为两个界各自会在另一个界的主场上失效

- 在 pool30 的稠密实例上，`L_PACK` 几乎从不高于 `L0`（关键路径主导）；实测 `L_IP-L0=0` 在 30/30 个根上。
- 在分区型实例上，`L0=OPT-1` 在 50/50 个实例上，`L_PACK=OPT` 在 50/50 个上。

所以不存在"一个更强的界"；存在的是一个**故障容忍的证书组合**：任何一个 provider 失效（超时/关闭），其余 provider 仍然给出可采纳下界；正确性不依赖于任何一个 provider 的存活，只依赖于"每个返回 NO 的 provider 都是可靠的"。这把 v0.7 的"单点精确判定"改造成了"多点冗余判定"。

这里的 fault-tolerant 是**fail-stop** 意义上的：provider 可以返回 `?`（超时、禁用、预算耗尽），但不会返回一个错误的 NO。组合规则是

```text
FT(σ,H) = NO   若存在一个存活的 provider 返回 NO
        = ?    否则
```

`?` 只会让算法更慢，不会让它更错。这是本轮对"fault-tolerant algorithm"的严格用法；不声称 Byzantine 容错。

## 但 v0.7 的 DEC 不能丢：PACK 只解决容量，sequencing 仍要精确判定

`PACK` 丢掉了优先约束。在 `L_PACK < OPT` 的实例上（容量有松弛，但顺序/尾长导致不可行），仍然需要 DEC。本轮把 `PACK` 放进 DEC 的**每个节点**：若当前残差连整数分箱都过不了，就不必再试 sequencing。这是 v0.7 "把能量界放到每个节点"的同一手法，只是换成了一个更强的整数界。

## backtracking：两个用法，一个正面一个负面

1. **正面**：m≥3 的 `PACK` 本身用回溯 B&B（大任务/资格集 fail-first，可选 L2 下界）；它是精确的，失败时给出一个不可行核。DEC 仍是带回溯的 DFS，阈值 memo 保留。
2. **负面**：我原本想用 PACK 的核做 conflict-directed backjumping。实测核在 exact-volume 实例上就是全体 `R`（和 v0.7 的 MUS 负结果同构），没有可跳过的独立决策；真正能跳的只有 deadline 冲突，而 deadline 冲突的 support 在稠密实例上只带来约 6% 的节点收益，且在 PACK 打开后边际收益为 0。所以 CBJ 只作为可选开关，不作为卖点。

## 结果（同一 harness，n=9–13，m=2/3）

- **DENSE30**：v0.7 基线 5,400 节点；节点级 PACK 4,218（−22%）；根 IP 界无增益（关键路径主导）。
- **PART2（30 个，m=2）**：基线 221,721 节点（中位 7,505，最大 17,109）；只用根 `L_PACK` 13 节点；只开节点 PACK 43 节点；两者都开 13 节点。
- **PART3（20 个，m=3）**：基线 437,920 节点（中位 15,742，最大 63,283）；只用根 `L_PACK` 11 节点；只开节点 PACK 31 节点；两者都开 11 节点。
- 全部 50 个分区实例 `L0=OPT-1`、`L_PACK=OPT`；`L_DFF` 单独闭合 20/50。
- 137 个随机状态（m=2/3）独立验证：105 个 NO 全部被 `ref.py` 确认，32 个 YES 全部从零重放，0 错。

## 与 v0.7 的关系：不是推翻，是加一层"整数包络"

v0.7 的 `L0 ≤ THRESH ≤ TENT ≤ DEC` 保留；本轮在 `L0` 与 `DEC` 之间插入 `L_DFF` 和 `L_PACK`。`L_PACK` 不是 DEC 的近似，它是 DEC 的一个**必要条件的精确解**；所以 `PACK=NO ⇒ DEC=NO`，但它比 `L0` 强，且比 DEC 便宜。证书层次变成：

```text
max(L0, L_DFF)  ≤  max(L0, L_PACK)  ≤  DEC（精确）
```

`L_DFF` 与 `L0` 不可比（关键路径 vs 分箱），所以用 `max` 而不是链式 `≤`。

## 本轮的一句话最大风险

**所有 17,000×/39,000× 的收益都来自"exact-volume、`L_PACK=OPT`"的合成分区族；在容量有松弛、`L_PACK<OPT` 的真实稀疏优先实例上，节点级 PACK 只带来约 9% 的剪枝，DEC 的最坏指数行为没有改变。**

# 产物区 · v0.8：X-DUB/IP*

> Integer-Packing certificate：把容量多面体的整数包络当作第二张证书  
> 中文名：整数分箱下界 + 逐节点容量剪枝的容错精确判定  
> 状态：设计稿 + DENSE30、PART2（30 个 m=2）、PART3（20 个 m=3）实验、四路消融、137 个状态独立验证、核大小与故障注入实验已完成；n≥14、m>3、PSPLIB 未做。

---

## 0. 版本关系与本轮增量

v0.7（X-DUB/EC*）的资产全部保留：

- `(R,A,est)` 状态、Q-DOM、focal + guide、路径最大下界 `F`、证明 DAG 的局部检查规则；
- 逐节点能量界 `E(R,A)`、截止期界、阈值 memo、`EC-SOLVE`；
- `L_A`、TENT/THRESH/AVAIL 与 `m=2` 的精确判定。

v0.8 只加三样东西，并且**不删** v0.7 的任何开关：

1. **IP-LB（整数分箱下界）**：`L_PACK(σ)=min{H : PACK(σ,H)}`。`PACK` 是"把 `R` 整数地分到 `m` 台机器、每台容量 `H-A_k`、每个任务在自己的 `[max(A_k,est_i), H-q_i]` 窗口内"的赋值松弛。它是可采纳下界，m=2 用 bitset 精确解，m≥3 用回溯 B&B 精确解。
2. **PACK-DEC（逐节点容量剪枝）**：在 DEC 的每个节点先跑 `PACK(σ,H)`；失败即 `NO`。这是 v0.7 "把能量界放到每个节点"的同一手法，只是把体积界换成了整数界。
3. **FT-PORT（fail-stop 证书组合）**：`L0 / L_DFF / L_PACK` 三个 provider 各自可超时、可禁用；组合规则是"取存活 provider 的最大下界 / 任一 NO 即 NO"。任何一个 provider 失效只损失性能，不损失正确性。

**与 v0.6 的 TENT/THRESH 的关系（避免重复发明）**：v0.6 的窗口证书 `window_infeasible_at` 已经包含 2-bin 打包；`(a,b)=(0,H)` 就是"全局 2-bin 打包"，只是没有逐任务的 `(C2)` 资格，而且只在外部搜索节点调用。本轮的 PACK 不是"第一次用分箱"，而是 (i) 把它提升为状态级可采纳下界 `L_PACK`，(ii) 加逐任务资格 `(C2)`，(iii) 放进 DEC 的每个节点，(iv) 补上 m≥3 的精确 B&B。这个定位比"新分箱"诚实，也是本轮真正的 delta。

关系：

```text
关闭 IP-LB + PACK-DEC + FT-PORT   → v0.7 的 X-DUB/EC*（EC-SOLVE + TENT）
只开 IP-LB                       → v0.7 搜索 + 更强的根下界
只开 PACK-DEC                    → v0.7 搜索 + 更强的逐节点剪枝
全部打开                         → v0.8 的 X-DUB/IP*
```

组合下界：

```text
L0(σ)    = max( C(σ), max_i(est_i+p_i+q_i), ceil(Σ_{i∈R}p_i/m) )
L_DFF(σ) = max_t  t · ceil( Σ_{i∈R} floor(p_i/t) / m )
L_PACK(σ)= min{ H : PACK(σ,H) }
L_IP(σ)  = max( L0, L_DFF, L_PACK )
L_X8(σ)  = max( L_IP(σ), L_EC(σ) )        # L_EC 仍由 DEC 的 NO 给出
```

因为 `L0 ≤ L_IP`，所以 `L_X8 ≥ L_X7`；关闭新开关后逐字回到 v0.7。

## 1. 符号（本轮新增）

| 符号 | 含义 |
|---|---|
| `R = V\S` | 未调度任务（位掩码） |
| `A=(A_1≤…≤A_m)` | 排序后的机器可用时间 |

| `PACK(σ,H)` | 赋值松弛：整数分箱 + 窗口资格，见 §3.2 |
| `L_PACK(σ)` | `min{H : PACK(σ,H)}`，整数包络下界 |

| `L_IP(σ)` | `max(L0,L_DFF,L_PACK)` |

| `CBJ` | conflict-directed backjumping（可选） |
| `T_PACK` | 允许在节点调用 `PACK` 的条件（`m=2` 或 `|R|≤κ`） |

`sl_i` 的符号约定与 v0.7 一致：`est_i` 是 heads，`H-q_i` 是 `i` 的最晚完成，故 `H-q_i-p_i` 是最晚开始。

## 2. 诊断：体积界与整数包络的缺口

### 2.1 v0.7 的 `E` 是体积界

**引理 1（v0.7 能量界）**：任意从 `σ=(R,A,est)` 出发、makespan 为 `C` 的完成满足 `E(R,A)≤C`。

**证明**：机器 `k` 在 `[A_k,C)` 内最多贡献 `C-A_k` 的工时，故 `Σ_R p ≤ mC-ΣA`。取整得证。证毕。

这个证明只用了"总工时"和"每台机器的容量"，没有用"任务不可分割"。因此它在分区型实例上会失效。

### 2.2 两个反例：一个体积松，一个体积恰好紧

**反例 A（体积松）**：`p=(6,6,6), m=2, H=11`。

```text
E = ceil(18/2) = 9 ≤ 11
但两台机器中总有一台放两个 6，负载 12 > 11
⇒ H=11 不可行，OPT=12
```

**反例 B（体积恰好紧）**：`p=(4,4,4,4,4,4,4), m=3, H=10`。

```text
E = ceil(28/3) = 10 = H
但每台机器最多放两个 4（3 个 4 是 12），三台最多 6 个 < 7 个
⇒ H=10 不可行，OPT=12
```

反例 B 是这一轮的关键：`E=H` 在根上取等号，在 DEC 的每个节点也取等号（因为 `Σp+ΣA` 守恒），所以 v0.7 的能量剪枝**恒不触发**。这正是 v0.7 §11.1 所担心的分区型风险的一个最小实现。

### 2.3 缺口可以随 `H` 线性增长

**定理 2（体积界的积分间隙）**：固定 `m≥2`。对任意 `H`，取 `m+1` 个大小 `s=floor(H/2)+1` 的任务。则 `H` 不可行，且

```text
E = ceil((m+1)s/m),      OPT = 2s,
H - E ≥ H(m-1)/(2m) - O(1).
```

**证明**：每台机器最多放一个任务（`2s>H`），`m+1` 个任务需要 `m+1` 台机器，故 `H` 不可行。最优调度把两个任务放同一台机器，`OPT=2s`。`E` 的表达式直接代入。对 `m=2`，`H-E≈H/4`。证毕。

这说明：**体积界的缺口不是"差一个单位"，而是可以随 `H` 线性增长**；v0.7 在 pool30 上看到 gap≤4，是稠密优先约束把关键路径抬高了，不是体积界本身变强了。

### 2.4 缺的信息是"整数性"

`E` 是容量多面体 `{x≥0 : Σ_i x_i ≤ mH, ...}` 的 LP/体积松弛；`PACK` 是同一个容量多面体的**整数包络**：

```text
LP/volume:  允许把任务切成任意实数份
PACK:       每个任务必须整体放进某一台机器
```

所以本轮的动作不是"再找一个更紧的松弛"，而是**把容量多面体的整数可行性精确解出来**，作为第二张证书。

## 3. 两个整数下界：DFF 与 PACK

### 3.1 `L_DFF`：调和 dual-feasible-function 界

对任意整数 `t≥1`，定义

```text
B_t(σ) = Σ_{i∈R} floor(p_i/t)
L_DFF(σ) = max( max(A), max_{t≥1} t·ceil(B_t(σ)/m) )
```

**定理 3（DFF 可采纳）**：`L_DFF(σ) ≤ OPT(σ)`。

**证明**：设最优完成 `π` 的 makespan 为 `C`。对每台机器 `k`，其上的任务总加工时间 `Σ_{i∈M_k}p_i ≤ C`，于是

```text
Σ_{i∈M_k} floor(p_i/t) ≤ floor( Σ_{i∈M_k} p_i / t ) ≤ floor(C/t).
```

对 `k` 求和：

```text
B_t(σ) ≤ m·floor(C/t) ≤ mC/t
⇒ C ≥ t·B_t(σ)/m
⇒ C ≥ t·ceil(B_t(σ)/m)     （C 是整数）
```

对 `t` 取 max。`max(A)` 是可采纳的已提交下界。证毕。

DFF 的意义：它是 `PACK` 的一个**便宜、单行可检查的松弛**。在 `PACK` 超时或 `m` 很大时，它是降级证书。它也是反例 A/B 的一个即时解释：

```text
反例 A: t=6, B_t=3, ceil(3/2)=2 ⇒ L_DFF=12=OPT
反例 B: t=4, B_t=7, ceil(7/3)=3 ⇒ L_DFF=12=OPT
```

但 DFF 不是精确的：反例 `p=(4,4,4,4,3,1), m=2, H=10` 中，`L_DFF=10` 而 `OPT=11`；它只能给出 10。

### 3.2 `L_PACK`：赋值松弛的精确下界

**定义（PACK）**：对状态 `σ=(R,A,est)` 与 horizon `H`，

```text
PACK(σ,H) = ∃ α:R→[m] 使得
  (C1) ∀k:  Σ_{i:α(i)=k} p_i ≤ H - A_k
  (C2) ∀i:  max(A_{α(i)}, est_i) + p_i + q_i ≤ H
```

`α` 是"任务→机器"的整数赋值。`(C1)` 是每台机器的容量；`(C2)` 是每个任务的窗口资格（它必须在 `H-q_i` 前完成，且不能早于 `max(A_k,est_i)`）。

**引理 4（PACK 是 DEC 的必要条件）**：若 `DEC(σ,H)=YES`，则 `PACK(σ,H)=YES`。

**证明**：取任一 `H`-可行调度 `π`。令 `α(i)` 为 `i` 在 `π` 中的机器，`s_i` 为开始时间。则 `s_i ≥ A_{α(i)}` 且 `s_i ≥ est_i`，所以 `s_i ≥ max(A_{α(i)},est_i)`；又 `s_i+p_i+q_i ≤ Cmax ≤ H`，得 `(C2)`。机器 `α(i)` 上的所有加工都在 `[A_{α(i)},H]` 内，总加工不超过 `H-A_{α(i)}`，得 `(C1)`。证毕。

**定理 5（`L_PACK` 可采纳）**：`L_PACK(σ)=min{H:PACK(σ,H)} ≤ OPT(σ)`。

**证明**：`PACK` 对 `H` 单调（`H` 增大时容量与窗口都变宽），所以最小值良定义。由引理 4，`OPT` 处 `PACK` 可行，故 `L_PACK≤OPT`。证毕。

**注意**：`PACK` 丢掉了优先约束和 sequencing，所以 `PACK=YES` 不意味着 `DEC=YES`；但 `PACK=NO` 意味着 `DEC=NO`。它是**单边可靠**的，这正是证书需要的方向。

### 3.3 m=2：bitset subset-sum

m=2 时 `PACK` 可以精确地化为带强制项的 2-bin 子集和：

1. 对每个 `i`，算资格集 `E_i={k : max(A_k,est_i)+p_i+q_i≤H}`。
2. 若 `E_i=∅`，返回 NO。
3. 若 `|E_i|=1`，强制 `i` 到该机器；扣减容量；若溢出，返回 NO。
4. 剩下的"双资格"任务用 bitset 子集和：`bits=1; for p: bits |= bits<<p`。设剩余总加工 `T`、两机剩余容量 `(c_0,c_1)`，则可行 iff `bits` 在区间 `[max(0,T-c_1), c_0]` 内有 1。

复杂度：`O(n·c_0/word)`，`c_0≤H`。这是精确的，不是启发式。

### 3.4 m≥3：带回溯的 bin-packing B&B

m≥3 时 `PACK` 是 bin packing（强 NP-hard），但 n≤13 时可以精确回溯：

```text
PACK-M3(R, caps, H):
  1  对每个 i 算资格集 E_i={k : max(A_k,est_i)+p_i+q_i≤H}
  2  （可选）L2 计数界：对每个阈值 t，
         #{i : p_i > t} > Σ_k floor(caps_k/t) ⇒ NO
  3  DFS(idx, bins):
       若 idx=|R|: 返回 YES
       对 k ∈ E_idx（按资格集大小、p 降序的 fail-first 顺序）:
         若 bins[k]≥p_idx: bins[k]-=p_idx; 递归; bins[k]+=p_idx
       返回 NO
```

这里**不做**"剩余容量相同的 bin 合并"：两个 bin 的容量可能相同，但资格集不同，合并会丢掉合法的赋值；这是 m≥3 与 m=2 的一个重要实现差异。

`L2` 计数界是 `PACK` 的一个必要条件（每台容量 `c` 的机器最多容纳 `floor(c/t)` 个大于 `t` 的任务），只用于剪枝，不改变精确性；本轮实现用"资格集大小 + 任务大小"的 fail-first 排序，没有单独启用 L2，也没有做 L2 的消融。最坏 `O(m^n)`；在本轮 n≤12、H≤25 的实例上，根调用在毫秒级。

### 3.5 组合下界

```text
L_IP(σ) = max( L0(σ), L_DFF(σ), L_PACK(σ) )
```

**定理 6（`L_IP` 可采纳）**：`L_IP(σ) ≤ OPT(σ)`。

**证明**：`L0` 是 v0.7 的可采纳下界；`L_DFF` 由定理 3；`L_PACK` 由定理 5。三者取 max 仍可采纳。证毕。

`L_IP` 的严格性来自两个方向：

- 在稠密实例上，`L0` 的关键路径项主导，`L_PACK` 通常不高于 `L0`；
- 在分区型实例上，`L0` 只有体积项，`L_PACK` 把它抬到 `OPT`。

## 4. PACK-DEC：逐节点整数剪枝

### 4.1 定义

对状态 `σ=(R,A,est)` 与 horizon `H`，`PACK-DEC` 在 v0.7 的 DEC 上增加一条节点级检查：

```text
(D4) PACK(σ,H) = NO  ⇒  返回 NO
```

`(D1)` 截止期、`(D2)` 能量、`(D3)` 阈值 memo 全部保留。`(D4)` 是必要条件，只删不可能的分支。

### 4.2 伪代码

```text
PACK-DEC(σ, H, memo):
  if R=∅: return YES([])
  if max(A)>H: return NO
  est,q ← HEADS-TAILS(σ)
  # (D1) 截止期
  if ∃i∈R: est_i+p_i+q_i>H: return NO
  # (D2) 能量
  if E(R,A)>H: return NO
  # (D3) 阈值 memo
  key ← (R,A,est_R)
  if memo.bad[key] ≥ H: return NO
  # (D4) 整数分箱
  if T_PACK(σ) and not PACK(σ,H):
      memo.bad[key] ← max(memo.bad[key], H)
      return NO
  # 分支：ready × machine，最早开始
  for i in READY(R) sorted by (H-q_i-p_i)-est_i:
      for k in 0..m-1:
          t ← max(A_k, est_i)
          if t+p_i+q_i>H: continue
          A' ← A with A'_k=t+p_i
          est' ← PROPAGATE(est, i, t+p_i)
          if PACK-DEC(R\{i}, A', H, memo) = YES:
              return YES([(i,k,t)] + child)
  memo.bad[key] ← max(memo.bad[key], H)
  return NO
```

`T_PACK` 是成本控制：`m=2` 时总是调用（`O(nH/word)`）；`m≥3` 时只在 `|R|≤κ`（本轮 κ=12）或 `H≤H_small` 时调用，否则退回 `E`/DFF。

### 4.3 CBJ：可选的回跳

v0.7 的 DEC 是时间序 DFS。本轮加了一个可选的 **conflict-directed backjumping** 模块，只为 deadline 冲突服务：

- 每个 `est_i` 维护一个 support 位掩码 `supp(est_i)`，记录"哪些决策层的完成时间产生了这个值"。
- 若在节点上 `est_i+p_i+q_i>H`，冲突集就是 `supp(est_i)`。
- 若当前决策层不在冲突集里，说明换当前决策也救不了，直接回跳到冲突集里最深的决策层；否则继续试兄弟。

**引理 7（support 可靠性）**：若两个前缀在 `supp(est_i)` 上一致，则第二个前缀下的 `est_i` 不小于第一个前缀下的 `est_i`。

**证明要点**：`supp(est_i)` 包含所有已调度的、对 `est_i` 有贡献的前驱决策层；未调度的前驱只能以 `est_j+p_j` 的形式贡献，任何替代前缀若把它调度了，其完成时间 `c_j≥est_j+p_j`，只会让 `est_i` 变大；若替代前缀不调度已在 support 里的前驱，则与"一致"矛盾。归纳得证。证毕。

由引理 7，deadline 违反在替换非 support 决策后仍然成立，所以 CBJ 是可靠的。**但实测它的边际收益很小**（§9.4）：PACK 打开后，DENSE30 上 CBJ 的额外节点收益为 0；PACK 关闭时也只有约 6%。因此默认配置建议 `PACK-DEC` 开、`CBJ` 关。

## 5. IP-SOLVE：把下界当作求解器

```text
IP-SOLVE(σ0)
1  U ← min(CP, LPT, MWKR)(σ0)          # 三条表调度的可行上界
2  L ← L0(σ0)
3  memo ← ∅
4  loop:
5      if PACK provider alive:
6          L ← max(L, L_DFF(σ0), L_PACK(σ0))
7      if L ≥ U: return (U, L, PROOF=IP)
8      r ← PACK-DEC(σ0, U-1, memo)
9      if r=NO:  return (U, U, PROOF=DEC)
10     if r=YES(π): U ← makespan(π); continue
11     if r=?:  return v0.7-FALLBACK(σ0, U, L)   # 预算耗尽
```

`L_PACK(σ0)` 在 `[L0, U-1]` 上二分：若 `PACK(σ0,U-1)=NO`，返回 `U`（第 7 行直接闭合）；否则返回最小的可行 `H`。

**定理 8（IP-SOLVE 正确）**：若算法返回 `U`，则 `U=OPT(σ0)`。

**证明**：`U` 始终是可行调度的 makespan，故 `OPT≤U`。

- 若在第 7 行返回，`L≥U`，而 `L≤OPT`（定理 6），故 `OPT=U`。
- 若在第 9 行返回，`DEC(σ0,U-1)=NO`，即不存在 `Cmax≤U-1` 的完成，故 `OPT≥U`；夹逼得 `OPT=U`。
- 第 10 行 `U` 严格下降（整数），且 `U≥OPT`，所以最多 `U0-L0+1` 轮；每轮要么下降、要么返回。证毕。

**终止性**：`U` 严格下降且下界 `L0` 固定，循环有限。

## 6. FT-PORT：fail-stop 证书组合

### 6.1 定义

一个 **provider** 是一个函数 `c_j(σ,H) ∈ {NO, OK, ?}`，满足

```text
c_j(σ,H)=NO  ⇒  DEC(σ,H)=NO.        （单边可靠性）
```

`OK` 表示"没有证明 NO"（不是"证明 YES"）；`?` 表示超时/禁用/预算耗尽。组合：

```text
FT(σ,H) = NO   若 ∃j∈alive: c_j(σ,H)=NO
        = ?    否则
```

下界组合：

```text
L_FT(σ) = max{ l_j(σ) : j∈alive },     l_j(σ) ≤ OPT(σ).
```

### 6.2 定理

**定理 9（fail-stop 可靠性）**：若每个存活的 provider 都满足单边可靠性，则 `FT=NO ⇒ DEC=NO`；若每个存活的 `l_j` 都可采纳，则 `L_FT≤OPT`。

**证明**：第一条由定义直接取一个返回 NO 的 provider；第二条由"有限个 ≤OPT 的数的 max ≤OPT"。证毕。

**推论（优雅降级）**：任意 provider 子集失效，只可能让 `FT` 从 `NO` 变成 `?`、让 `L_FT` 变小；不会产生错误的 NO，也不会产生高于 `OPT` 的下界。若 `PACK-DEC` 仍在 `alive` 里且预算足够，完备性不受影响。

**边界**：这是 fail-stop，不是 Byzantine。一个"返回错误 NO"的 provider 会破坏可靠性；要防它，必须给每个 NO 配一个独立可检查的 witness，并由一个可靠的 checker 验证。本轮只做了抽样验证（§9.5），没有实现全量 proof-DAG checker。

### 6.3 三个 provider 的分工

| provider | 成本 | 强项 | 弱项 |
|---|---|---|---|
| `L0` | `O(n+|E|)` | 关键路径、稠密优先 | 分区型只有体积项 |
| `L_DFF` | `O(n·pmax)` | 大任务计数、单行证书 | 不是精确分箱 |
| `L_PACK` | m=2 `O(nH/word)`；m≥3 指数 | 整数分箱、分区型 | 丢优先/sequencing；m≥3 贵 |

三者取 max，任何一个失效都不会让下界高于 `OPT`；任何一个返回 NO 都不会让答案变错。

## 8. 复杂度

### 8.1 单次 `PACK`

```text
m=2:  O(n·H/word)          # bitset 子集和 + 强制项
m≥3:  O(m^n) 最坏           # 回溯 B&B；资格集 fail-first 只降常数
```

### 8.2 单次 `PACK-DEC`

```text
时间: O( N_dec · ( |R| + m|R|H + T_PACK ) )
空间: O( S_dec · (m+n) ) + memo
```

`N_dec` 是 DEC 节点数，`S_dec` 是不同 `(R,A,est_R)` 状态数。最坏 `N_dec=O((mn)^n)`；`PACK` 只改变常数/实际节点数，不改变最坏复杂度。

### 8.3 `L_PACK` 的二分

```text
m=2:  O(log U · n·H/word)
m≥3:  O(log U · T_PACK)
```

### 8.4 与 v0.7 的对比

| 对象 | 最坏复杂度 | 实测（本轮） |
|---|---|---:|
| v0.7 DEC（能量） | 指数 | DENSE30 5,400 节点 |
| PACK-DEC m=2 | 指数（同阶） | DENSE30 4,218；PART2 43 |
| PACK-DEC m=3 | 指数（同阶） | PART3 31 |
| `L_PACK` m=2 | `O(log U·nH/word)` | 30 个 PART2 根，毫秒级 |
| `L_PACK` m=3 | `O(log U·m^n)` | 20 个 PART3 根，毫秒级 |

`L_PACK` 没有改变 `PACK-DEC` 的最坏复杂度；它改变的是"根上能不能不做搜索"。

## 9. 实验设计

### 9.1 数据与验证

- **DENSE30**：v0.7 的 30 个 `n=9–10, m=2` 困难实例，`OPT` 由独立精确 DFS 给出。
- **PART2**：30 个新生成的 `m=2` 实例，`n=10–13`，`p_i∈[2,9]`，总加工为偶数，且**不存在**恰好一半的子集和；由 subset-sum 精确得 `OPT=H+1`，`H=总/2`。因此 `L0=H=OPT-1`、`L_PACK=OPT`。
- **PART3**：20 个新生成的 `m=3` 实例，`n=9–12`，`p_i∈[2,7]`，总加工为 3 的倍数，且 3-bin 在 `H=总/3` 处不可行；由负载向量 DP 精确得 `OPT=H+1`。因此 `L0=H=OPT-1`、`L_PACK=OPT`。
- **独立验证器 `ref.py`**：不用 est 传播，每个节点从 `c` 向量重算开始时间；对 DEC 的每个 NO 交叉验证，对每个 YES 从零重放（前驱、机器不重叠、截止期）。
- **时间**：纯 Python 3.12，单线程，单次测量；只用于相对比较。PACK 的内部 B&B 节点不计入 DEC 节点数，但计入时间。

### 9.2 反例与手算核对

| 实例 | `m` | `H` | `E` | `L_DFF` | `PACK` | `OPT` |
|---|---:|---:|---:|---:|---|---:|
| `(6,6,6)` | 2 | 11 | 9 | 12 | NO | 12 |
| `(4×7)` | 3 | 10 | 10 | 12 | NO | 12 |
| `(4,4,4,4,3,1)` | 2 | 10 | 10 | 10 | NO | 11 |
| `(8,8,8,3,3)` | 2 | 15 | 15 | 16 | NO | 16 |

第一行说明体积界可以松 3；第二行说明 `E=H` 但整数分箱仍不可行；第三行说明 DFF 不是精确的（10 vs 11），必须靠 PACK；第四行说明大任务计数可以很小。

### 9.3 主结果：DENSE30

**单次根判定（H=OPT−1）**：

| 变体 | DEC 节点 | 时间 | 根 `L=OPT` |
|---|---:|---:|---:|
| v0.7 基线（E + 截止期 + memo） | 3,502 | 0.016 s | 23/30 |
| + 节点 PACK | 3,192 | 0.018 s | 23/30 |
| + 节点 PACK + CBJ | 3,192 | 0.019 s | 23/30 |

> 注：这里的 baseline 是 v0.7 的 **DEC 骨架**（`E` + 截止期 + memo），不含 TENT 根证书；v0.7 完整版在 pool30 上根闭合 29/30。本轮只替换 DEC 内部与根下界，TENT 仍可原样叠加；所以 23/30 不是"v0.7 变差了"，而是"同一骨架下 PACK 的增量"。

只有 3 个根有收益：

| k | OPT | 基线 | +PACK | 比值 |
|---:|---:|---:|---:|---:|
| 11 | 41 | 653 | 575 | 1.14× |
| 13 | 27 | 299 | 109 | 2.74× |
| 14 | 18 | 123 | 81 | 1.52× |

其余 27 个根在 1 个节点内闭合。**诚实解读**：在稠密实例上，`PACK` 不是主角；它的作用是"不伤害"，并为分区型实例保留同一套代码。

**完整 IP-SOLVE（含 `U0` 的多轮）**：

| 配置 | DEC 节点 | 时间 | `U=OPT` |
|---|---:|---:|---:|
| base（仅 v0.7） | 5,400 | 0.025 s | 30/30 |
| 仅节点 PACK | 4,218 | 0.027 s | 30/30 |
| 仅 IP 下界 | 5,400 | 0.027 s | 30/30 |
| full（IP + PACK + CBJ） | **4,218** | 0.029 s | 30/30 |

IP 下界在 DENSE30 上 0 增益：`L_IP-L0=0` 在 30/30 个根上。原因是关键路径项 `max_i(est_i+p_i+q_i)` 已经等于或超过分箱界。

### 9.4 主结果：PART2 / PART3

**完整 IP-SOLVE**：

| 族 | 数量 | `L0=OPT-1` | `L_IP=OPT` | base 节点 | 仅节点 PACK | 仅 IP 下界 | full | base 时间 | full 时间 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| PART2 | 30 | 30/30 | 30/30 | 221,721 | 43 | 13 | **13** | 0.85 s | 0.00 s |
| PART3 | 20 | 20/20 | 20/20 | 437,920 | 31 | 11 | **11** | 1.56 s | 0.001 s |

`base` 节点分布：

```text
PART2: 中位 7,505，P90 10,561，最大 17,109
PART3: 中位 15,742，P90 44,914，最大 63,283
```

代表性实例：

| 族 | k | n | OPT | base | full |
|---|---:|---:|---:|---:|---:|
| PART2 | 12 | 13 | 38 | 17,109 | 1 |
| PART2 | 6 | 12 | 48 | 2,975 | 13 |
| PART2 | 0 | 12 | 38 | 9,941 | 1 |
| PART3 | 14 | 12 | 18 | 63,283 | 1 |
| PART3 | 9 | 10 | 18 | 54,442 | 1 |
| PART3 | 1 | 10 | 19 | 44,914 | 1 |

`full` 在 48/50 个分区实例上 0 个 DEC 节点（根 `L_IP=OPT` 直接闭合）；PART2 的 k=6（13 节点）与 PART3 的 k=3（11 节点）因为 `U0=OPT+1`，各跑了一次 DEC 找到更优调度。**这里没有"节点数换时间"的魔法：根 `PACK` 一次调用就把整个搜索替代了。**

### 9.5 四路消融：两个 provider 各自独立

| 族 | base | 仅节点 PACK | 仅 IP 下界 | full |
|---|---:|---:|---:|---:|
| DENSE30 | 5,400 | **4,218** | 5,400 | **4,218** |
| PART2 | 221,721 | 43 | 13 | **13** |
| PART3 | 437,920 | 31 | 11 | **11** |
| 错误数 | 0 | 0 | 0 | 0 |

两个结论：

1. **在分区族上，两个 provider 各自都能把指数搜索压到 O(1)**：只开节点 PACK 是 43/31 节点，只开 IP 下界是 13/11 节点；
2. **在稠密族上，IP 下界 0 增益，节点 PACK 约 22%**。这正是 fault-tolerant 的意义：没有一个 provider 在所有族上都强，但组合不会比任何一个差。

### 9.6 DFF 的单独作用

| 族 | `L_DFF=OPT`（原始值） | 说明 |
|---|---:|---|
| DENSE30 | 19/30 | L0 自己闭合 23/30；`max(L0,L_DFF)` 不增加闭合数 |
| PART2 | 11/30 | 剩余 19 个需要 PACK |
| PART3 | 9/20 | 剩余 11 个需要 PACK |

DFF 是"PACK 超时时的降级证书"：在 20/50 个分区实例上，它不用任何搜索就能闭合；其余实例退回 PACK 或 DEC。它不是主角，但它让 `alive` 集合在 PACK 失效时仍有非平凡下界。

### 9.7 核大小：一个诚实的负结果

对 `H=OPT-1` 的 PACK 失败实例，做贪心删任务求最小不可行核（MIS）：

| 族 | 核大小 | 结论 |
|---|---|---|
| PART2（exact-volume） | 10–13，中位 12；30/30 等于 `|R|` | 核是全局的 |
| PART3（exact-volume） | 7–12，中位 9.5 | 核接近全局 |
| `(8,8,8,3,3)` | 3 | 大任务核很小 |
| `(4,4,4,4,3,1)` | 5 | 中等 |
| `(4×7), m=3` | 7 | 全局 |
| `(4×6,3,3), m=3` | 8 | 全局 |

这与 v0.7 的 MUS 负结果同构：**在 exact-volume 实例上，"不可行"不是少数任务造成的；PACK 的力量来自精确判定本身，不来自小核。** 因此本轮没有把核用于 backjumping；CBJ 只处理 deadline 冲突。

### 9.8 CBJ 的边际收益

| 配置 | DENSE30 节点 | 说明 |
|---|---:|---|
| 无 PACK、无 CBJ | 3,502 | 基线 |
| 无 PACK、有 CBJ | 3,295 | −5.9% |
| 有 PACK、无 CBJ | 3,192 | — |
| 有 PACK、有 CBJ | 3,192 | **0 额外收益** |

CBJ 在实例 13 上把 299 降到 52（无 PACK 时），但在实例 11 上从 653 升到 693（回跳改变了搜索顺序，memo 命中变化）。总体上它不是一个稳定的收益；默认建议关闭。

### 9.9 可靠性验证

- **137 个随机状态**（m=2 与 m=3 混合，`n=8–11`，随机前缀与随机 `H∈[L0,U-1]`）：
  - 105 个 `NO` 全部用 `ref.py` 独立确认，0 个假阳性；
  - 32 个 `YES` 全部从零重放（前驱、机器、截止期），0 个坏见证；
  - `PACK-DEC` 与 base 的状态判定 0 个不一致。
- **50 个分区实例**：`L_PACK=OPT` 与 brute-force 负载 DP 逐一核对，0 个不一致。
- **全部 DENSE30 + PART2 + PART3**：`U=OPT`，0 个错误。
- 没有实现全量 proof-DAG checker；这是抽样验证，不是形式证明检查。

### 9.10 fail-stop 故障注入

用开关模拟 provider 失效（不是实际超时，但语义相同：该 provider 返回 `?`）：

| 配置 | DENSE30 | PART2 | PART3 | 错误数 |
|---|---:|---:|---:|---:|
| full（三个 provider + PACK-DEC） | 4,218 | 13 | 11 | 0 |
| 只关 IP 下界（保留节点 PACK） | 4,218 | 43 | 31 | 0 |
| 只关节点 PACK（保留 IP 下界） | 5,400 | 13 | 11 | 0 |
| 全关（退回 v0.7） | 5,400 | 221,721 | 437,920 | 0 |

这张表就是"优雅降级"：最坏情况下退回 v0.7 的指数搜索，但**没有一行出现错误答案**。反过来，如果只信一个 provider 而在它失效时没有 fallback，就会从 13 节点退化到 221,721 节点——性能故障，不是正确性故障。

## 10. 负结果与边界

1. **PACK 是经典 bin packing**：`L_PACK` 不是新松弛；本轮的新意是"把它作为状态级可采纳下界 + 逐节点剪枝 + 与 v0.7 的 DEC 组合"，不是"发明了分箱"。
2. **稠密族上 IP 下界 0 增益**：`L_IP-L0=0` 在 30/30 个 DENSE30 根上。关键路径主导时，整数包络没有额外信息。
3. **核是全局的**：exact-volume 族上 MIS=`R`（30/30），和 v0.7 的 MUS 负结果同构；核不能用于 backjumping。
4. **CBJ 边际收益为 0（PACK 打开后）**：只在无 PACK 时有约 6%，且在一个实例上反而更慢。
5. **DFF 不精确**：20/50 个分区实例靠 DFF 闭合，其余必须 PACK；DFF 不能替代 PACK。
6. **m≥3 的 PACK 是指数的**：本轮 n≤12；n=14 以上没有数据，不能外推。
7. **没有 m>3、没有 n≥14 稠密、没有 PSPLIB**。
8. **没有全量 proof checker**：105 个 NO 的独立验证是抽样。
9. **时间是单次纯 Python**：0.00 s 的 full 时间是"根上闭合"的测量，不应解释为稳定的常数级优势。
10. **`U0` 依赖**：`L_PACK` 让根闭合，但如果 `U0` 很松，仍要跑 DEC 改进 `U`；本轮 PART3 有 1 个实例因此跑了 11 个节点。

---

## 11. 已知风险

1. **合成分区族的选择偏差**：PART2/PART3 是**按 `L_PACK=OPT` 构造**的；真实稀疏优先实例通常有容量松弛，`L_PACK<OPT`，此时节点级 PACK 只带来约 9% 的剪枝（DENSE30 的 3/30 个根），指数 DEC 仍在。这是最大风险。
2. **PACK 丢优先约束**：它只能证明"容量/整数性"导致的不可行；对"顺序/尾长"导致的不可行无能为力。`L_PACK<OPT` 的实例仍需 DEC。
3. **m≥3 的成本**：PACK 的 B&B 在 n=13、H=50 时可能变慢；`T_PACK` 的阈值是经验性的，没有理论保证。
4. **DFF 的降级是弱的**：DFF 在 30/50 个分区实例上不能闭合；如果 PACK 超时，仍可能退回指数 DEC。
5. **CBJ 的实现复杂性**：support 位掩码在 `est` 重算时需要仔细维护；本轮只做了 137 个状态的抽样验证，没有形式化检查器。
6. **核的负结果**：不能把 PACK 的核当作"小解释"；在 exact-volume 族上它就是全体。
7. **fail-stop 不是 Byzantine**：一个返回错误 NO 的 PACK 会直接破坏正确性；本轮只做了抽样交叉验证，没有全量 witness checker。
8. **机器身份**：v0.7 的"排序 A 导致见证机器编号错位"的 bug 仍然是一个提醒；本轮 PACK 只返回布尔值，调度见证仍由 DEC 返回，必须保留机器身份。
9. **时间测量**：所有时间都是纯 Python 单次，不能当作稳定常数。
10. **没有大规模基准**：n≥14、m>3、PSPLIB 全部未做。

---

## 12. 一句话最大风险

**本轮 17,000×/39,000× 的收益全部来自"exact-volume、`L_PACK=OPT`"的合成分区族；在容量有松弛、`L_PACK<OPT` 的真实稀疏优先实例上，节点级 PACK 只带来约 9% 的剪枝，DEC 的最坏指数行为没有改变。**
