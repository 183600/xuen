# 第 10 轮（新灵感循环第 1 轮；本轮灵感：「路径规划」×「应用落地」）
> **基线**：第 9 轮 MetricVoiceGauge-ACMD（定义 532–539；引理 82–86；实验 E551–E570）。
> 本轮纪律：**全局路径证书 + 参数溯源 + 部署能力信封**。两个灵感分别治理 v9 的两笔债：**全局性债**（块证书只覆盖未来约 200ms，局部有效的块不保证存在局部有效的续接——"每一步都安全"不等于"这条路走得通"）与**落地债**（v9 是一套实验室栈：证书默认模型/标定/地图不变，从未回答"凭什么敢在真实场地、真实硬件、真实维护节奏下宣称能力"）。新模块必须保持 v9 的**可选增强 + 中立元退化**纪律：CCP/PIV/DCE 任一失效 ⇒ 注入对应中立元，严格退回 v9（引理 91），且**只做减法**——部署门只会缩小动作集，绝不放大。

## 0. 直觉与动机

**灵感 1（路径规划 → 证书携带的路径，Certificate-Carrying Path, CCP）**
直觉：v9 的 ActionChunkCertifier 像一个只看眼前 200ms 的司机：每个动作块都有块证书和中止点，但没有任何机制保证"下一块仍然存在"。在走廊尽头、门口、电梯口这类拓扑关键处，局部安全会把人送进一个**没有认证续接**的死角——安全（能停下）但失去活性（任务失败，甚至堵住通道）。更严格的提法是把路径规划的输出从"路点序列"升级为**路径证书**：σ 是一条路径，[h] 是它相对障碍集的同调签名，g⁻ 是整条走廊的间隙下界，e⁺ 是能量/时间上界，A 是沿途认证中止锚点集，prov 是它依赖的参数溯源。核心创新：**证书携带路径规划器（CCP）** 与**路径证书复合算子 ⊙**：当块 k 的终态落在块 k+1 的入口区且签名一致时，复合证书继承 min 间隙下界与中止可达性（引理 87），于是"块级安全"第一次可以复合成"航线级安全"。一个诚实的技术选择：≥3D 配置空间里同伦判定昂贵甚至不可判定，故只用**同调签名（H₁ 绕数/链接数）作为必要条件**——签名变化必失效，签名不变仍须几何复核；这是保守、可计算的近似，不是完备同伦分类。

**灵感 2（应用落地 → 证据加权的能力信封，Deployment Capability Envelope, DCE）**
直觉：实验室问"它能不能跑"，落地问的是"我**凭什么**宣称它能跑、在什么硬件/场地/维护状态下能跑、以及什么时候必须停止宣称"。这两问的差别是**证据与责任**，不是算法。核心创新：**部署能力信封（DCE）**：C 把（任务类、环境类、风险类）映射到（成功率下界 p⁻、安全违背上界 q⁺、证据束编号）；部署门只放行落在 C 内且证据束可追溯的动作。配套 **证据束（EvidenceBundle）** 把每条论文/产品主张绑定到仿真、受控场地、影子日志、认证测试等证据项及其统计保证；没有证据的主张不允许进入信封。关键纪律：**扩张要证据，收缩只需一次事故**——放宽 C 必须通过预注册的 anytime-valid 序贯检验（e-process），而任何一次安全违背立即无条件收缩（引理 91 的单调性）。

**灵感 3（综合 → 参数溯源：证书是参数的租约，不是永恒真理）**
直觉：路径证书里的 g⁻、e⁺、刹车距离全都依赖摩擦系数、标定纪元、传感器健康、地图版本、固件哈希。实验室默认这些不变；落地时它们**天天在变**（地面湿滑、轮胎磨损、相机温漂、地图被同事编辑）。若证书不携带"我依赖了哪些参数、这些参数现在是否仍在声明区间内"，它就在纸面上永远有效、在物理上随时失效。核心创新：**参数溯源记录 prov 与依赖图 D(prov)**：证书只在其依赖参数仍处于声明区间且未超过**陈旧 horizon λ_stale** 时有效；任一依赖变化只失效**依赖它的**证书（定向失效），而不是全图重规划。这把 v9 的"模型不变"隐含假设显式化为一个可监控、可审计、可失效的契约。

## 1. 研究问题（轮次升级版）

- **Q1（全局复合）**：局部块证书在什么联结条件下可复合成航线证书，且继承的间隙下界是保守的？如何用同调签名做"必要的失效检测"而不背上不可判定的同伦判定？如何避免"局部安全→全局死角"的承诺陷阱，同时不把系统变成过度保守的"停在原地"？
- **Q2（溯源与定向失效）**：如何表示参数的溯源依赖，使校准/传感器/地图/固件变化在一个规划纪元内只失效受影响的证书？陈旧 horizon λ_stale 如何标定？哪些隐式耦合（温度→摩擦、磨损→里程计+制动）无法被人工依赖图捕获，需要独立探针？
- **Q3（部署能力边界）**：如何构造证据加权的 C，使被放行动作集恒为 v9 动作集的子集？如何用 e-process 让 C 的扩张 anytime-valid、而收缩零延迟？如何抵抗落地压力下的"证据通胀"（把弱证据当强证据、用仿真覆盖率冒充现场保证）？
- **Q4（可辨识边界）**：证书的保证不可能超过其参数溯源的保真度。哪些参数耦合在部署可观测量下不可辨识？需要哪类独立挑战测试（低速制动、标定板、地图审计）才能把"纸面有效"升级为"物理有效"？

## 2. 设计原则（在 P10–P12 基础上新增 P13–P15）

**P13 证书携带路径律（Certificate-Carrying Path, CCP）**
高风险航行必须以路径证书 P=(σ,[h],g⁻,e⁺,A,prov) 为单位；仅当 A 非空、prov 有效、且下一块终态落在已认证续接的入口区时才执行当前块。块内仍由 v9 AC 守卫；块间由 ⊙ 复合继承航线级下界。同调签名变化、续接缺失、或规划超时 ⇒ 不"赌"续接，退回 v9 局部块（活性下降、安全不变）。

**P14 溯源失效律（Provenance Invalidation, PIV）**
每个证书声明它使用的参数及可接受区间，并注册到依赖图 D(prov)。任一依赖离开区间、或证书年龄超过 λ_stale、或溯源哈希不匹配 ⇒ 该证书在一个规划纪元内失效，系统降为 K_eff=1 安全停驻，直到重新标定/复核。禁止"继承未复核的参数"；未溯源参数非空时，高风险任务必须放大安全裕度或拒绝。

**P15 部署能力信封律（Deployment Capability Envelope, DCE）**
部署只放行 C 内且证据可追溯的（任务、环境、风险）组合；被放行动作集 A_t^adm = A_t^{v9} ∩ {证书有效 ∧ 能力获准}，故恒为 v9 子集。C 的扩张必须预注册并通过 anytime-valid 序贯检验；任何安全违背立即收缩。安全关键模块 φ^elig=false，永不因"降本/提速"被能力门移除。

**P13–P15 与退化的关系**：CCP 关闭 ⇒ 等价 v9 的 AC-only；PIV 关闭 ⇒ 源固定为 last-known-good、证书退化为 v9 的"模型不变"假设（这是**降低保证**而非提高能力，必须在日志中显式标注）；DCE 关闭 ⇒ 实验室/影子模式，撤销对外能力主张。

## 3. 与基线的接口（如何退化）

- 路径证书失效（同调签名变化 / 无认证续接 / 规划超时）⇒ 丢回 v9 AC 局部块，K_eff 按 v9 门控；安全保持、活性下降；
- 溯源失效（参数越界 / λ_stale 到期 / 哈希不匹配）⇒ K_eff←1 + 安全停驻，等待重标定；这是 v9 动作集的保守子集；
- 部署门失效（证据束缺失 / C 未覆盖）⇒ 撤销能力、进入监督/影子模式；不产生 v9 不会产生的动作；
- v9 的 AC/MW/ID 任一失效 ⇒ v9 中立元；再退回 v8 的 DA/SPR/Cal 中立元；全失效 ⇒ v7 → v6。

## 4. 预期贡献

1. **证书携带路径规划**：把"局部块安全"升级为可复合的"航线安全"，用同调签名做保守失效检测，给出复合继承引理与续接证书；
2. **参数溯源与定向失效**：把 v9 隐含的"模型/标定/地图不变"变成显式、可监控、可定向失效的租约，附陈旧 horizon 与隐式耦合审计；
3. **证据加权部署信封**：把"能不能跑"升级为"敢宣称什么"，给出扩张/收缩不对称的统计纪律，抵抗证据通胀；
4. **落地闭环实验 E571–E590**：复合继承、同调检测时延、定向失效精度、陈旧注入、信封校准、现场序贯检验、对抗地图/标定、长跑漂移、端到端任务。

## 5. 本轮最大风险

**一句话**：落地压力会系统性地奖励"证据写宽一点、溯源依赖写少一点"，而证书失效检测又依赖人工声明的依赖图——最大的风险不是证书算错，而是**证书所依赖的参数已经悄悄变了、依赖图却不知道**，于是系统在最像"一切正常"的时刻执行一份事实上已过期的安全承诺。

# 第 10 轮产物 · 创新点清单 v10：**MetricVoiceGauge-CCPD**（Certificate-Carrying Path planning + Provenance-aware Invalidation + Deployment Capability Envelope）

> 背景：第 9 轮 MetricVoiceGauge-ACMD（定义 532–539；引理 82–86；实验 E551–E570）。
> 本轮灵感：「路径规划」×「应用落地」
> **继承纪律**：MetricVoiceGauge 九不变式（CVC-闭环、SpatialCert、RT-CVC、FaultCert、PrimitiveGraph、严格退化链、OTL、GCT、ER）全部保留；v9 的 AC/MW/ID 与 v8 的 DA-ML/SPR/Cal 原样继承。新组件一律为**可选增强**：任一新环节不可用 ⇒ 注入中立元，严格退回 v9 行为（引理 89/90/92），而非行为漂移。核心铁律：**证书是参数的租约，不是永恒真理；部署门只做减法，不做加法。**

**新增定义 540（路径证书 PathCertificate）** 路径证书是路径规划的输出单元：
```
P = (σ, [h], g⁻, e⁺, A, ρ, prov)
```
其中 σ:[0,1]→X_free(t_plan)；[h] 为相对障碍集 O(t_plan) 的同调签名（2D 用绕数向量，3D 用链接数/环绕数，仅在可计算时使用；不可计算时退化为"签名 = 拓扑特征标签"的保守占位）；`g⁻ = min_{s∈σ}(dist(σ(s),O) − r_body) − ε_disc` 为考虑离散化 slack 的间隙下界；`e⁺` 为摩擦区间 [μ⁻,μ⁺] 下速度剖面的能量/时间上界；A={(s_i,v_i)} 为规划时刻满足停车不变式的锚点；ρ 为有效期（时间或弧长）；prov 见定义 543。有效性谓词：
```
Valid(P,t) ⇔ t − t_plan ≤ ρ ∧ [h(σ;O(t))] = [h]
             ∧ g⁻(t) ≥ d_safe ∧ (∀a∈A: AnchorReachable(a,t))
             ∧ Covers(prov_t, prov_P)
```
注意：`g⁻` 在 t 时刻用当前障碍集做保守距离场复核；若 5Hz 全量复核过贵，则采用"5Hz 边际审计 + 租约到期全量复核"的两级检查（引理 92 预算）。

**新增定义 541（同调走廊 Homology Corridor）** `Cor(P) = {σ' : [h(σ';O)] = [h]}`，其不变量元组 `I(P) = (g⁻, e⁺, A, ρ)`。走廊成员判定是保守的：签名不同 ⇒ 必定不在同一走廊；签名相同仍须几何复核（同调粗于同伦，可能把不同伦的路径判为同签名）。这一"必要非充分"的方向保证：**签名变化必然触发失效，不会漏报拓扑阻断；但可能误报，故只做保守降级，不做乐观放行。**

**新增定义 542（路径复合 RouteComposition ⊙）** `P₁₂ = P₁ ⊙ P₂` 有定义当且仅当：
1. 联结相容：`‖σ₁(1) − σ₂(0)‖ ≤ ε_join`；
2. 签名一致：`[h₁] = [h₂]`（拼接后签名不变）；
3. 锚点可停：存在 a ∈ A₁ 在联结邻域内可认证停驻，或 a_join 新认证；
4. 溯源相容：`prov₁ ⊓ prov₂ ≠ ⊥`，其中 `⊓` 对依赖取并、对区间取交；区间不相交 ⇒ 复合无定义（禁止用两套矛盾参数拼一条航线）。

结果：
```
P₁₂ = (σ₁·σ₂, [h], min(g₁⁻,g₂⁻) − ε_join, e₁⁺ + e₂⁺,
       A₁ ∪ A₂ ∪ {a_join}, min(ρ₁,ρ₂), prov₁ ⊓ prov₂)
```
`ε_join` 吸收联结处的位置/朝向不连续与离散化误差。重要后果：**⊙ 只在"松弛意义"下结合**——m 次复合累积 m·ε_join 的保守损失，故航线级 `g⁻` 必须扣除累计罚项 `m·ε_join`，或每 m_max 块做一次全量复核（引理 87 的诚实边界）。

**新增定义 543（溯源记录与依赖图 ProvenanceRecord & Dependency Graph）** 溯源记录 `prov=(ce, [μ⁻,μ⁺], h_sensor, m_ver, fw_hash, model_hash, t_cal)`；依赖图 D 把每个证书映射到它实际使用的参数键集合（如 `friction`, `cam_intrinsic`, `wheel_radius`, `map_tile_17`, `brake_gain`, `load_model`）。更新事件 `δ=(key,new_value,t)` 触发**定向失效**：
```
Invalidated(P) ⇔ ∃ key ∈ D(P): new_value ∉ declared_interval_P(key)
                 ∨ t − t_cal > λ_stale
                 ∨ hash(prov_P) ≠ hash(prov_t)
```
未溯源参数 `U(P) = params_used(P) \ ⋃_m D(m)`。规则：`U(P) ≠ ∅` 时，高风险任务必须（i）放大 d_safe、缩小 K_max，或（ii）拒绝执行；禁止把"没有监控"当作"没有变化"。依赖图由人声明，是**假设**而非定理（引理 93）。

**新增定义 544（证书租约 CertificateLease）** 每张证书携带租约 `(epoch, expiry=t_plan+ρ, prov_hash, revocable)`。epoch 单调递增；任一标定/地图/固件/模型更新使 epoch 自增；持有旧 epoch 的证书立即失效。租约可被**撤销**（revoke），撤销广播到多机共享层；撤销与过期都走同一失效路径。租约把"证书有效性"从长期属性变成**有截止时间、可吊销的授权**。

**新增定义 545（部署能力信封 DeploymentCapabilityEnvelope）** `C: (T,E,R) → (p⁻,q⁺,e_id)`，T 为任务类（导航/抓取/交接/移动操作），E 为环境类（结构化/半结构化/人群/湿滑/低照度），R 为风险类（可逆/不可逆/人身邻近）。放行谓词：
```
Adm(t,e,r) ⇔ ∃ entry: p⁻ ≥ p_min(r) ∧ q⁺ ≤ q_max(r)
             ∧ EvidenceValid(e_id) ∧ Valid(P,t)
```
风险越高，p_min 越大、q_max 越小。信封偏序：`C₁ ⊑ C₂` 当且仅当 ∀ 三元组 `p⁻₁ ≤ p⁻₂ ∧ q⁺₁ ≥ q⁺₂`（C₁ 更保守）。扩张 = 上移，收缩 = 下移。

**新增定义 546（证据束 EvidenceBundle）** `E = {(claim, item, cov, ℓ, g)}`，证据强度等级：E0 轶事 < E1 仅仿真 < E2 影子日志 < E3 受控场地 < E4 预注册随机现场 < E5 形式化验证 + 运行时监控。主张 `claim` 可入信封仅当存在证据项满足 `ℓ ≥ ℓ_min(claim 的风险类)` 且 `g` 覆盖该主张。**组合规则：** 多条弱证据不得"并集"成强证据；依赖链上的保证取**最小强度/最弱环节**（min-rule），而非平均或投票。雾件（"正在做"）与未预注册的事后统计不得计入。

**新增定义 547（现场序贯检验 FieldSequentialTest）** 对信封条目 `(t,e,r)` 的成功率假设 `H₀: p ≤ p₀` 维护 e-process `E_t(μ₀)=∏(1+λ_i(μ₀−X_i))`。由 Ville 不等式，`P(∃t: E_t ≥ 1/α) ≤ α`。扩张规则：仅当 `E_t ≥ 1/α` 且扩张已预注册，才允许把 `p⁻` 上调（或 `q⁺` 下调）。收缩规则：**任何一次安全违背立即无条件下移信封到保守底线，无需统计检验**。扩张与收缩的不对称是本设计的核心：**加能力要证据，减能力只要是事故。**

**新增定义 548（溯源/能力感知动作集 Provenance-Aware Action Set）** `A_t^adm = A_t^{v9} ∩ {a : G_joint(t,a)}`。由于只是附加合取，`A_t^adm ⊆ A_t^{v9}`（引理 90）。若 `U(P) ≠ ∅`，用保守版本 `A_t^{adm,cons}`（放大 d_safe、K_max←min(K_max,3)）进一步取子集。绝不出现"门控通过后动作集比 v9 更大"的情况。

**新增定义 549（能力-路径联合门与中立元 Joint Gate & Neutral Elements）**
```
G_joint(t,a) = Valid(P,t) ∧ Covers(prov_t, prov_P) ∧ Adm(t,e,r) ∧ LeaseValid(P,t)
```
中立元（失败即注入，严格退回 v9）：
- `v_CCP^⊥`：无航线 ⇒ 丢弃 P，仅用 v9 AC 局部块（K_eff 按 v9 门控）；
- `v_PIV^⊥`：prov 冻结于 last-known-good，所有证书按 v9 的"模型不变"处理，日志置 assurance-reduced；
- `v_DCE^⊥`：撤销能力主张，进入 lab/shadow；对外输出 `capability=none`。
三者组合仍是 v9 的保守子集（引理 92）。

δ_trigger = {σ < τ_safe ∧ γ_grasp valid ∧ Δ_dom < τ_dom ∧ risk_SLAM < τ_SLAM

**升级定义 531（软硬约束衔接，v10）** M₀ 硬检查新增两个入口：(i) 航线租约过期/撤销；(ii) 溯源失效且系统未在 1 个规划纪元内进入 K_eff=1 停驻。两者与块级违规同权重，直接触发安全停驻。

# IP-357 CertificateCarryingPlanner：证书携带路径规划
@dataclass
class RouteCertificate:
    path: list            # σ
    homology: tuple       # [h]
    g_minus: float        # g⁻
    e_plus: float         # e⁺
    anchors: list         # A = [(s_i, v_i)]
    horizon: float        # ρ (s)
    prov: dict            # prov
    t_plan: float

    def valid(self, t, obs, prov_now):
        if t - self.t_plan > self.horizon:
            return False
        if obs.homology(self.path) != self.homology:       # 必要失效检测
            return False
        if obs.clearance_lb(self.path) < self.g_minus:     # 保守几何复核
            return False
        if any(not obs.anchor_reachable(a) for a in self.anchors):
            return False
        return prov_now.covers(self.prov)                   # 定义 543

class CertificateCarryingPlanner:
    def __init__(self, sampler, coll, max_join=0.03, eps_penalty=0.01,
                 m_max=5, horizon=2.0):
        self.sampler, self.coll = sampler, coll
        self.max_join, self.eps_penalty = max_join, eps_penalty
        self.m_max, self.horizon = m_max, horizon

    def plan(self, s0, goal, obs, prov, t):
        raw = self.sampler.plan(s0, goal, obs)              # RRT*/PRM
        if raw is None:
            return None
        sig = obs.homology(raw)
        g = obs.clearance_lb(raw) - obs.robot_radius() - obs.disc_slack()
        e = obs.energy_ub(raw, prov.friction_interval())    # 用 [μ⁻,μ⁺] 上界
        anchors = [a for a in obs.candidate_anchors(raw)
                   if obs.stopping_invariant(a)]
        if g < obs.d_safe or not anchors:
            return None
        return RouteCertificate(raw, sig, g, e, anchors,
                                self.horizon, prov, t)

def compose(P1, P2, eps_join, eps_penalty):
    if dist(P1.path[-1], P2.path[0]) > eps_join: return None
    if P1.homology != P2.homology: return None
    prov = prov_join(P1.prov, P2.prov)        # 依赖取并，区间取交
    if prov is None: return None              # 区间不相交 => 无定义

# IP-358 ProvenanceTracker：参数溯源与定向失效
class ProvenanceTracker:
    def __init__(self, lam_stale=600.0):
        self.deps = {}            # cert_id -> set(param keys)
        self.intervals = {}       # cert_id -> {key: (lo, hi)}
        self.cal_time = {}        # cert_id -> t_cal
        self.epoch = 0
        self.revoked = set()

    def register(self, cert_id, prov):
        self.deps[cert_id] = set(prov["params"])
        self.intervals[cert_id] = dict(prov["intervals"])
        self.cal_time[cert_id] = prov["t_cal"]

    def on_update(self, key, value, t):
        self.epoch += 1
        for cid, keys in self.deps.items():
            if key not in keys:
                continue                                # 定向：只碰依赖者
            lo, hi = self.intervals[cid].get(key, (None, None))
            out_of_range = not (lo <= value <= hi)
            stale = (t - self.cal_time[cid]) > lam_stale
            if out_of_range or stale:
                self.revoke(cid)

    def revoke(self, cid):
        self.revoked.add(cid)                           # 定义 544

    def untraced(self, cert):
        used = set(cert.prov["params"])
        monitored = set().union(*self.deps.values()) if self.deps else set()
        return used - monitored                         # U(P)，定义 543


# IP-359 DeploymentGate：证据加权部署门
class DeploymentGate:
    def __init__(self, envelope, bundle, p_min, q_max, alpha=0.05):
        self.C, self.E = envelope, bundle
        self.p_min, self.q_max, self.alpha = p_min, q_max, alpha
        self.eprocess = {}

    def admit(self, task, env, risk):
        entry = self.C.get((task, env, risk))
        if entry is None:
            return False
        return (entry.p_lb >= self.p_min(risk)
                and entry.q_ub <= self.q_max(risk)
                and self.E.valid(entry.evidence_id))      # 定义 545/546

    def field_update(self, task, env, risk, outcome):
        if outcome.safety_violation:
            self.C.shrink_to_floor(task, env, risk)       # 零延迟收缩
            return
        ep = self.eprocess.setdefault((task, env, risk), EProcess())
        ep.update(outcome.success)
        if ep.value >= 1.0 / self.alpha:
            self.C.expand_if_preregistered(task, env, risk)  # 定义 547

## 4. 推导

**引理 87（路径复合继承与松弛结合性）** 设 `P₁₂ = P₁ ⊙ P₂` 按定义 542 有定义。则 (i) 对任意 `x ∈ σ₁·σ₂`，`dist(x,O) ≥ min(g₁⁻,g₂⁻) − ε_join`（保守间隙下界）；(ii) 任一 `a ∈ A₁∪A₂∪{a_join}` 在 t 时刻若通过 `AnchorReachable` 复核，则从 a 停驻满足停车不变式；(iii) 能量/时间上界 `≤ e₁⁺+e₂⁺`。证明：(i) 两段分别有 `g₁⁻,g₂⁻` 下界，联结邻域用三角不等式引入 `ε_join` 罚项；(ii) 锚点集只增不减，新增 a_join 由构造认证，旧锚点须经当前复核（定义 540 的 Valid 条件）；(iii) 能量沿路径可加，摩擦区间取交后 `e⁺` 仍是上界。结合性：`(P₁⊙P₂)⊙P₃` 与 `P₁⊙(P₂⊙P₃)` 的路径与签名相同，但前者累计联结罚项的顺序不同，二者相差至多 `2ε_join`；故只能称**松弛结合**。实现上限制 `m ≤ m_max=5` 并每 m_max 块全量复核，避免罚项无限累积。∎

**引理 88（同调失效检测的保守性与时延界）** 设感知时延 ≤ τ_p，动态障碍最大速度 ≤ v_o，走廊最小拓扑特征尺度 ≥ δ。若真实障碍集变化使旧签名类被阻断，则真实签名必在 `τ_p + δ/v_o` 内改变，检测器（比较 `[h(σ;O(t))]` 与证书签名）在此期间触发。证明：签名改变要求障碍穿越走廊的拓扑特征（闭合缺口/通道），障碍需移动至少 δ 才能改变该特征；感知给出变化的最晚时刻为真实时刻 + τ_p，故触发时延 ≤ τ_p + δ/v_o。注意三项边界：(a) 该界是**条件性**的，遮挡、感知漏检、突发高速物体会破坏 v_o 假设；(b) 同调是粗于同伦的不变量，签名不变**不**保证续接存在（假阴性方向由几何复核与锚点检查补足）；(c) 签名改变可能只是新增独立环绕、并不真正阻断，故检测会**保守误报**——误报只导致降级，不导致不安全。∎

**引理 89（溯源失效的保守退化）** 若 `¬Covers(prov_t,prov_P)` 或 `LeaseValid=false` 或 `U(P)≠∅` 且任务高风险，则系统执行 `K_eff=1` 安全停驻（或保守动作集 `A_t^{adm,cons}`）。该动作集是 v9 动作集的子集，且停驻安全性由 v9 引理 82 在 K=1 时保证。证明：由定义 548/549，注入 `v_PIV^⊥` 后仅保留 v9 的 K=1 路径；v9 引理 82 的 K=1 情形不依赖块证书跨步外推，故成立。`A_t^{adm,cons}` 仅通过放大 d_safe 与缩小 K_max 取子集。∎

**引理 90（能力门子集性）** 对任意 t，`A_t^adm ⊆ A_t^{v9}`。证明：`A_t^adm` 是 `A_t^{v9}` 与 `{a : G_joint(t,a)}` 的交；`G_joint` 是附加合取谓词，删除元素不增加元素。特别地，`v_DCE^⊥` 时 `A_t^adm=∅`（只保留安全停驻，停驻是 v9 已有的安全动作）。∎

**引理 91（证据单调性与非通胀）** 在无安全违背的路径上，加入证据只会使 `C` 在偏序 `⊑` 上不降（`p⁻` 不降、`q⁺` 不升）；任何安全违背立即使 `C` 降至保守底线。扩张由 e-process 拒绝 `H₀` 控制：`P(错误扩张) ≤ α`（Ville 不等式）。证据强度组合取 min-rule，依赖链最弱环节决定主张强度，故多条弱证据的并集不能伪造强主张；未预注册的事后统计不计入。∎

**引理 92（端到端安全归约与预算）** 对任一实际执行的动作 `a_t`，只有两种情形：(i) `G_joint(t,a_t)` 成立且 `a_t` 位于有效航线证书的走廊内 ⇒ 由引理 87 的 `g⁻ ≥ d_safe` 与锚点可达性，v9 引理 82 在块级继续适用；(ii) `G_joint` 失败 ⇒ 系统按引理 89 安全停驻，v9 引理 82 的 K=1 情形适用。故 v10 的不可安全集不大于 v9，新模块没有引入新的不安全动作。预算：CCP 在 5Hz 边界运行 ≤15ms（摊销 ≤1.5ms/cycle）；溯源事件驱动 O(|deps|) ≤0.2ms；部署门任务边界 O(1)；航线有效时 50Hz 只多一次租约比较（≤0.05ms）。决策侧典型 ≤9ms、p99 ≤20ms，50Hz 保持；若 CCP 超时则 `v_CCP^⊥` 直落 v9 AC，不阻塞安全闭环。∎

**引理 93（隐式耦合不可辨识）** 存在两个物理世界 w、w′，其真实摩擦/标定轨迹不同，但在声明依赖图 D 下产生**逐位相同**的可观测流与 prov 记录（例如：摩擦与轮径同步漂移，使里程计读数与制动观测在激励不足的方向上完全一致；或温度同时影响电池与摩擦，而温度未被 D 覆盖）。任何仅以 D 内参数为输入的监视器在 w、w′ 上输出相同判决，故无法区分"证书仍有效"与"证书已物理失效"。因此：(a) 依赖图完整性是**假设**，不可由系统自证；(b) 必须引入独立挑战测试（低速制动测摩擦、标定板测内参、地图审计测版本、已知负载测增益）；(c) 系统的安全主张只能是**条件保证**（给定溯源保真），不是无条件证明。∎

## 8. 预期趋势（预测，非实测）

- 复合后航线级 `g⁻` 比块级最小间隙保守 `m·ε_join`（m=5 时约 5cm 量级），换来确定性的航线安全；
- 同调检测在 v_o≤1m/s 时中位时延 ~80ms，p99 ~180ms，误报率随障碍密度上升但只触发降级；
- 定向失效把重规划算力从 O(全图) 降到 O(受影响子图)，预期重规划次数相同时算力 ↓80%+；
- 溯源陈旧注入下，系统在 1 个周期内进入 K_eff=1 停驻，突破率 0（在依赖图完整的受控实验 E575 中）；
- 部署信封在分任务/分环境下校准偏差 <5%，但**跨环境外推**会出现系统性低估（预期 ≥10% 偏差），这正是 E585/E590 要暴露的 sim-to-real gap；
- 端到端相对 v9 的任务收益主要来自"少走死路/少无效重规划"，预期 +10%~+15%，而非单步更聪明。

## 9. 本轮最大风险

**一句话**：落地压力会系统性地奖励"证据写宽一点、溯源依赖写少一点"，而证书失效检测又依赖人工声明的依赖图——最大的风险不是证书算错，而是**证书所依赖的参数已经悄悄变了、依赖图却不知道**（引理 93 的不可辨识性），于是系统在最像"一切正常"的时刻执行一份事实上已过期的安全承诺。
