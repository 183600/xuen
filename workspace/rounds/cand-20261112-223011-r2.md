# 第 2 轮迭代（灵感循环 v3：「人形机器人」×「模块化设计」）—— 从「扰动后恢复」转向「具身模块化」：躯干参考系 + 双臂守位 + 泛化轴正交模块

> **本轮是"换表征 + 用身体"，不是再加一条数据管线。** 承接 v2（UIP-01′~15，Gazebo×实时性×模块化），本轮把两个新词读成两个**被浪费的自由度**：
> 1）**人形机器人被当成"固定机械臂"用**——接口只给 `lower_body[15]` 与 base 系 ee pose，而公开数据集里明明有 `waist_state_joint[3]`、`*_ee_pose_gripper_torso[6]`、`state_torso[6]`、`action.waist_action_joint[3]`、`base_command[4]`；多数提交会把共享的 `action.pivot[7]` 置零或当噪声，**把一个可动机身用成了支架**。
> 2）**模块化被做成"按任务切模型"**——但泛化有 5 条正交轴（未见物/人扰/位置/干扰物/背景），真正该正交的是 **技能轴 × 泛化轴**，而不是 32 份权重。
> 一句话判断：**v2 在"补数据"，v3 在"改表示、用冗余、正交分解"**——前者抬高上限，后者降低方差。

**本轮最强的两个新推论：**

- **R1（表征错配）**：公开数据用**躯干系**监督最自然（`*_ee_pose_gripper_torso` 现成），但接口的 ee 输入/输出用**base 系**。若不做显式换系，腰一动，策略看到的 ee 误差就混入"躯干在动"这一 nuisance——在插网线、合盖、拉链这类 ±5mm/±5° 决定成败的步上，这是系统性误差源。
- **R2（双臂未用）**：`human_*` 里至少 11 个任务是"把已完成进度撤回"（T08/T10/T11/T12/T14/T16/T17/T19/T24/T25/T26/T27/T29…）。v2 的应对是"发现被撤回→重做"；**人形机器人有第二只手臂，可以在物理上守位/阻挡/扶稳**，把"事后恢复"变成"事中阻断"。

## 2. 两个灵感词：直觉解释 → 严谨定义

### 2.1 人形机器人
- **直觉**：人形机器人不是"装在架子上的机械臂"。它有**可动躯干（腰）**和**两条手臂**；头随躯干动，腕随手动。人类做桌面任务时会"侧身、探腰、另一只手扶住"，这正是当前提交普遍浪费的自由度。
- **严谨定义**：本赛题的 G1 在被评测的桌面场景中是一个**固定底座、带 3-DoF 腰的冗余双臂链**；信号分布在三个参考系——base（接口 ee pose 系）、torso（腰以上，头/双臂的根）、hand（腕相机与夹爪）。**一个"具身一致"的策略应把状态与动作尽量表达在 torso 系**：因为 `left_arm/right_arm` 关节角本来就是 torso 系，腕相机是 hand 系，头相机是 torso 系——只有 base 系 ee pose 是"异类"。把异类换回 torso 系，整个观测就变成**对腰/底座运动不变的身体中心表示**。

### 2.2 模块化设计
- **直觉**：模块化不是"32 个任务→32 个模型"，甚至不只是"10 个技能头"。真正的模块化是**沿独立变化方向分解**：任务在变（技能），环境在变（泛化轴）；把两者做成**正交两维**，才能组合泛化，而不是为每个交叉点存权重。
- **严谨定义**：一个模块化策略 `M = (f_θ, {S_s}, {A_a}, C, r)`：共享骨干 `f_θ`；技能模块 `S_s`（抓/放/插/拧/拉链/折叠/堆叠/分拣/开合/挑取）；泛化轴适配器 `A_a`（unseen-object / human / position / distractor / background）；每个模块带**类型化契约** `C=(pre, post, 必需观测, 必需执行器, 失败模式, 回退)`；路由器 `r(obs, language)` 在 episode 起点给出稀疏激活组合。**部署时仍是一个 checkpoint、一条骨干、每个 episode 一条前向路径**——满足"单模型"的合规解释。

## 3. 瓶颈假设（v3）

- **H1（表征）**：base 系 ee pose 与 torso 系关节角混用，会让腰部小动作被误读为"手在动"，在精细接触步（插网线/合盖/拉链）直接吃成功率。
- **H2（冗余）**：3-DoF 腰是**免费工作空间 + 主动视角**（转腰让头相机看到遮挡区），但也是**平衡与可信度风险**；必须小步、平滑、低频，并用 `lower_body` 监测底座是否被带动。
- **H3（双臂）**：对"反向撤回"型人扰，**守位（物理阻挡/扶稳/占位）**比"检测后重做"更省步骤分，因为它在干扰发生前后都减少"已得分被清零"。
- **H4（正交）**：5 条泛化轴可分离 ⇒ 轴适配器 + 路由 > 单体大模型 > 32 个任务模型；但**路由错误会跨轴污染**。
- **H5（实时，沿用）**：开环大块 + 多帧堆叠 = 高延迟/高方差；腰的额外维度不要增加推理负担。
- **H6（感知缺失）**：无力/触觉 ⇒ 守位接触与被撤回只能从 **pose 残差 + 腕部视觉 + 物体关键点反向位移** 推断，误报会触发无谓重做。

## 4. 候选 → v3 清单（详见产物区）

围绕两词发散 7 个草案，合并后：**旗舰 A · UIP-16 TAM（躯干系动作模块化）× 旗舰 B · UIP-17 BGS（双臂守位）**，由 **UIP-18 GAA（技能×泛化轴二维模块）** 承载模块化，**UIP-19 MSC（形态契约）** 保证跨 DoF/末端可移植；v2 的 GSO/DRF/ACS/CSG 继续作为"离线判分—造数据—控时—护栏"四件套。v3 的新颖点不在于"再训练一个更大的模型"，而在于**先修正身体表征，再把第二条手臂用于对抗人为撤回**。

## 5. 本轮最大风险（一句话）

**若正式评测中腰关节被锁死、或 `action.pivot[7]` 的语义与"腰 3 + base 4"的推断不符，则 TAM/BGS 的大半收益会瞬间归零——因此第一件事必须是用公开数据的双帧位姿做 FK 一致性验证，而不是先训模型。**

## 1. 旗舰 A · UIP-16 TAM（Torso-Aware action Modularity）

### 1.1 直觉
策略在两个混用的参考系里工作：关节角天然是**躯干系**（手臂挂在腰上），而接口给的 ee pose 是**base 系**。腰只要动一点，base 系 ee 的"误差"就同时包含"手没到位"和"躯干在动"两件事。精细接触步要求的是**手相对躯干/物体的误差**，不是相对底座的误差。TAM 把这件事显式拆开：**策略在 torso 系里思考，接口在 base 系里收发，换系由已知的腰角在线完成。**

### 1.2 严谨定义
设有 3 个腰关节角 `q_w ∈ R³`（从 `observation.state.lower_body` 中按 URDF 取出），前向运动学 `T(q_w) = T_base_torso(q_w) ∈ SE(3)`。数据集对同一 ee 同时给出 `p^base_t` 与 `p^torso_t`，满足（理想情形）

```
p^base_t = T(q_w,t) · p^torso_t          (1)
```

定义策略分解 `π = (σ, φ, ψ)`：

- `σ: obs → Δq_w^{cmd}`：低频**腰调度器**，只在"够不到 / 视角被挡 / 关节接近限位"时给小增量；
- `φ: (obs, {p^torso}) → {Δp^torso}`：在 torso 系预测每臂的末端增量（与腰/底座运动**解耦**）；
- `ψ`：执行映射。

部署时：

```
joint 模式：q_arm^cmd = IK_torso( exp(Δp^torso) · p^torso )      (2a)
ee    模式：p^base_cmd = T(q_w + Δq_w^cmd) · exp(Δp^torso) · p^torso   (2b)
```

式 (2a) 成立的关键事实：**`action.left_arm/right_arm` 的关节角本来就是相对躯干的**，所以 torso 系预测与 joint 模式天然对齐；式 (2b) 则是 ee 模式必须做的换系——这一步正是绝大多数基线缺失的。

**一致性正则（可直接从数据学）**：对数据集中每个时刻，最小化

```
L_frame = || log( T(q_w)^{-1} · T_base_ee · T_torso_ee^{-1} ) ||²_F   (3)
```

其中 `T_base_ee`、`T_torso_ee` 由 `*_ee_pose_gripper_base` / `*_ee_pose_gripper_torso` 构造。它同时检验"腰角→躯干位姿"的 FK 是否正确，可作为**免费的物理自监督**。

### 1.3 为什么这是"人形"独有的杠杆
- **可达性**：3-DoF 腰把工作空间从"双肩固定"扩展为"可探身"；远/低/角落物体（T01 挂杯架、T08 书架、T23 球拍）可少走一步。
- **主动视角**：头相机随腰转；当目标被手臂或遮挡物挡住时，**转腰**比"移到侧面再回来"便宜得多，且不消耗步骤分。
- **表征一致性**：把 base 系 ee 换成 torso 系后，观测与关节动作同系，网络不必再花容量学"腰在动"。
- **安全边界**：固定底座下腰只做小角度；用 `lower_body` 监测底座是否被带动，若底座姿态变化则**立即冻结腰**、退回纯手臂策略。

### 1.4 落地步骤
1. **解析接口**：把 `lower_body[15]` 按 URDF 切成腿(12)+腰(3)（或腰(3)+腿(12)，E201 两种都试）。
2. **建 FK**：从 G1 URDF 取 `T_base_torso(q_w)`；在公开数据上验证式 (1) 的残差（E201）。
3. **换系层**：输入侧把 `*_ee_pose_gripper_base` 转 torso 系；输出侧按 (2a)/(2b) 回转。
4. **腰调度**：以数据集中腰角的分布为先验，`|Δq_w|` 设上限（如 ≤5°/步、≤15°/episode），平滑滤波；`pivot` 其余分量置零或保持默认。
5. **联合训练**：主轴用 torso 系动作；加式 (3) 作辅助 loss；用 UIP-11 GSO 回放验证。

### 1.5 风险
腰角排列/`pivot` 语义若与推断不符，换系会把误差放大而非消除；因此 **E201 是 go/no-go 门槛**，不过关就退回 joint 模式纯手臂版（此时 TAM 只剩"观测换系"的弱收益）。

## 2. 旗舰 B · UIP-17 BGS（Bimanual Guard Skill）

### 2.1 直觉
`human_*` 干扰的本质是"人伸手把你刚做完的步骤反向撤销"。v2 的做法是"看到退回→再做一遍"，代价是至少一次重做。**人形机器人有第二只手**：在操作手干活时，另一只手可以**扶住容器、挡住已完成区域、占住关键位**。很多干扰（翻开毛巾、拉开拉链、拿走锁、拿下第二个碗）在物理上会被一只守位的手显著拖慢或阻断；即便挡不住，守位手的 pose 残差也能**更早**触发恢复。

### 2.2 严谨定义
技能 `S` 有子目标序列 `g_1..g_n` 与操作臂 `h_m ∈ {L,R}`。BGS 是一个**可插入技能图的守位节点**：

```
BGS(S) = 在 S 的每个已完成子目标 g_i 周围选守位区域 G_i
         由空闲臂 h_g = {L,R}\{h_m} 维持 pose ∈ G_i
         直到 S 结束或检测到人扰
```

**守位区域选择**（离线用 GSO/DRF 搜索，在线用规则）：
`G_i = argmax_G [ 阻断收益(G) − 腕相机遮挡(G) − 关节代价(G) ]`，约束守位手不进入操作手的腕相机视锥、不与当前轨迹碰撞。

**人扰检测信号（无力的条件下）**：
- `r_pose`：操作手 ee 预测位姿与实际位姿残差突增且方向与进度相反；
- `r_vis`：腕/头相机检测到"外来手"进入 `G_i` 邻域；
- `r_obj`：物体关键点沿"撤回方向"位移（如拉链头回退、盖子重新合上）；
- `r_guard`：守位手自身 pose 被外力顶开（接触的间接证据）。
四项做轻量融合；`r_vis ∨ r_obj` 触发**守位加压**，`r_pose ∨ r_obj` 触发**重做**（复用 UIP-09′），两者都受 UIP-15 的次数/延迟预算约束。

### 2.3 与 v2 的差异
v2 是"事后检测→重做"；BGS 是"**事中守位→（挡不住再）重做**"。多出的收益来自：已得步骤分被清零的概率下降，且守位手提供的接触信号比纯视觉更早。

### 2.4 落地步骤
1. 在 11+ 个撤回型任务上标注"守位点"（见 §5 表）；
2. 用 GSO 搜守位区域，DRF 生成"守位成功/被绕过/守位接触"三类数据；
3. 训练一个**守位头**（与主策略共享骨干），输出守位手的目标 pose；
4. 与 UIP-01′ 状态机联调：守位节点插入在"刚完成子目标"之后、下一子目标之前。

### 2.5 风险
守位手可能**挡住腕相机**或与操作手碰撞，反而降低成功率；必须把"腕相机遮挡"写进守位区域的目标函数，并在 E204 里做消融。

## 3. 模块化 · UIP-18 GAA + UIP-19 MSC

### 3.1 UIP-18 GAA：技能轴 × 泛化轴的二维模块
**直觉**：任务变化来自两个独立方向——"做什么"（技能）与"环境怎么变"（泛化轴）。把它们做成二维矩阵，任一新任务 = 某个技能组合 × 某组激活的轴适配器；不必为 32 个交叉点各存一份权重。

**定义**：`f(x) = f_θ(x) + Σ_a w_a · A_a(h)`，`h = f_θ(x)`；`A_a` 为 5 个低秩适配器（object / human / position / distractor / background），`w = r(obs, language)` 由**内部小头**给出（OOD 物体分数、外来手检测、关键点位移、异常物体计数、场景偏移）。**路由在 episode 起点算一次**并固定，随后可把被激活的适配器合并进骨干 ⇒ 部署仍是单 checkpoint、单前向路径，满足单模型合规。

### 3.2 UIP-19 MSC：形态感知技能契约
每个技能是一个**带类型签名的模块**：

```
Skill = {
  pre:    进入条件（物体可见/夹爪空/子目标未完成）,
  post:   退出条件（与计分点对齐的几何谓词）,
  obs:    必需观测键（最小集，控制带宽）,
  act:    必需执行器（腰? 双臂? Dex1?）,
  invariants: 守位/不碰撞/不越限位,
  fail:   失败模式与回退（降级到单臂/无腰版本）,
  budget: 最大步数 + 延迟预算

```

价值：G1 存在 23/29 DoF 等不同配置，末端也可能是 Dex1 或其他夹爪；契约让同一技能图在**缺腰/缺指**时自动回退，而不是整套策略失效。这也把"模块化"从网络结构延伸到**可验证的软件接口**。

### 3.3 合规说明
所有适配器、守位头、路由器小头**共享同一条视觉-语言骨干并打包在同一 checkpoint**；在 episode 起点路由后可按权重合并，运行期不做外部模型调用。避免 v2 曾担心的"外部 VLM 验证器 = 非单模型"。

## 6. 关键伪代码

### 6.1 TAM 换系 + 腰调度

```python
import numpy as np

class TorsoAwarePolicy:
    def __init__(self, backbone, fk_base_torso, ik_torso,
                 control_space="ee", H=8):
        self.net = backbone
        self.fk = fk_base_torso      # q_w(3) -> SE(3) base<-torso
        self.ik = ik_torso           # torso->arm joints
        self.space = control_space
        self.H = H

    def _q_waist(self, obs):
        lb = np.asarray(obs["observation.state.lower_body"])
        lb = lb.reshape(-1, 15)[-1]           # 取当前帧
        return lb[12:15]                      # 假设: 腿12 + 腰3；E201 另试 lb[0:3]

    def _to_torso(self, p_base, T):
        # p_base: [x,y,z,r,p,y] -> SE(3)
        return np.linalg.inv(T) @ pose_to_se3(p_base)

    def get_action(self, obs):
        q_w = self._q_waist(obs)
        T = self.fk(q_w)

        ee_t = {s: self._to_torso(
                    obs[f"observation.state.{s}_ee_pose_gripper_base"], T)
                for s in ("left", "right")}

        d_t, dq_w, grippers = self.net(obs, ee_t)   # torso 系增量 + 腰增量
        T_cmd = self.fk(q_w + clip(dq_w, -0.09, 0.09))  # ~5°/步上限

        out = {
            "meta.token": self.token,
            "action.pivot": np.concatenate([dq_w, np.zeros(4)])[None].repeat(self.H, 0),
            "action.left_gripper":  grippers["left"][None].repeat(self.H, 0),
            "action.right_gripper": grippers["right"][None].repeat(self.H, 0),
        }
        if self.space == "joint":
            for s in ("left", "right"):
                tgt = se3_exp(d_t[s]) @ ee_t[s]
                out[f"action.{s}_arm"] = self.ik(tgt)[None].repeat(self.H, 0)
        else:
            for s in ("left", "right"):
                tgt = T_cmd @ se3_exp(d_t[s]) @ ee_t[s]     # 回 base 系
                out[f"action.{s}_ee_pose_gripper_base"] = se3_to_pose(tgt)[None].repeat(self.H, 0)
        return out
```

### 6.2 BGS 守位状态机

```python
class BimanualGuard:
    def __init__(self, verifier, guard_head, max_redo=2, max_guard_steps=30):
        self.verify = verifier
        self.guard = guard_head
        self.max_redo = max_redo

    def select_guard_arm(self, skill, obs):
        # 默认取非操作臂；若技能需双臂，退化为"腕部/前臂占位"
        return "right" if skill.manip_arm == "left" else "left"

    def step(self, obs, skill):
        g = self.verify(obs, skill.subgoal)       # done/ongoing/regressed
        h_g = self.select_guard_arm(skill, obs)

        if g == "regressed":
            return self.redo(skill.subgoal, guard=h_g)     # 事后兜底 (UIP-09′)
        if self.human_near(obs, skill.subgoal.region):
            return self.guard_press(h_g, skill.subgoal.region)  # 事中阻断
        if self.progress(obs, skill) == "subgoal_done":
            skill.advance()
            return self.guard_hold(h_g, skill.prev_subgoal.region)  # 守已完成区
        return self.manipulate(skill.manip_arm, skill.subgoal)
```

## 8. 合规与风险（本轮新增）

- **单模型合规**：所有适配器/守位头/路由小头共享一条骨干、打包一个 checkpoint；episode 起点路由后可合并，运行期不调外部模型。避免外部 VLM 验证器带来的"非单模型"风险。
- **参考系正确性**：`pivot` 语义、`lower_body` 排列、URDF 版本都可能导致换系错误；E201 不过关就不上线 TAM 主路径。
- **守位的副作用**：遮挡腕相机、碰撞、动作统计异常都会伤可信度与成功率；必须把遮挡与碰撞写进守位目标函数，并受 UIP-15 约束。
- **腰的安全**：固定底座下腰只做小角度、平滑、低频；一旦 `lower_body` 显示底座被带动，立即冻结腰。
- **仿真过拟合**：GSO/DRF 仍是结构裁判；真机锚点不可省。
- **手册仍未取到**：5 轴中的"位置/干扰物/背景"与"评测轮次/时限/控制频率"仍待飞书手册公开后核实。

## 10. 本轮结论与最大风险

**押注**：**UIP-16 TAM × UIP-17 BGS** 组成的"身体中心 + 双臂守位"操控回路——它把 v2"事后恢复"升级为"事中阻断"，并用 torso 系消除一个系统性表征误差；**UIP-18 GAA** 负责把收益泛化到 5 条轴，**UIP-19 MSC** 保证跨形态不崩。三者都在选手 API 权限与离线算力之内，且第一道门槛（E201）当天可验。

**本轮最大风险（一句话）**：腰关节若在正式评测中被锁死或 `pivot` 语义不符，TAM/BGS 的主要收益会归零，因此必须先用 E201 证伪/证实，再决定是否把"用腰"作为主线。
