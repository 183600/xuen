# 灵感循环 v3 · 第 1 轮（承接 v2）：「虚拟仿真」×「多语言支持」—— 把指令编译成"仿真可验证的语义程序"

> **本轮做的是"补地基"，不是给 v2 再叠一层模块。** v2 的旗舰 UIP-01′ 是"扰动感知的滚动验证-重做"，它默认了一件事：**验证器知道当前子目标是什么**。但子目标从哪来？来自任务语义；任务语义从哪来？来自 `observation.language` 这一条**自然语言字符串**。本轮把这条被忽略的链路翻上来，得到两个新地基：
>
> 1. **多语言支持的正确单位不是"语言"，而是"语义程序"**——公开数据的 `meta/tasks.parquet` 里，每个任务的 `task` 字段不是一句话，而是 **5 条英文改写用 `@` 连接**（32 个数据集逐一核实）。也就是说，"同义改写"已经是公开数据的一部分，而评测只给你其中或之外的一条字符串；**真正的不变量是语义，不是词面**。
> 2. **虚拟仿真的新用途不是"造更多动作"，而是"给语义提供可执行标签"**——只在仿真里，你能把世界按住不动（同一帧、同一条动作轨迹），只替换指令字符串，做一次干净的 `do(language := l′)` 干预；也只有在仿真里，你能廉价地把 32 任务 × 5 改写 × K 语言全部跑一遍，验证"这句话编译出的程序是否真的能执行到计分点"。
>
> **一句话：把语言变成可被仿真验证的程序，再把语言当作域随机化的一个新维度；多语言是保险，多改写才是已被证据支持的确定性收益。**

## 2. 两个灵感词：先直觉，再定义

### 2.1 虚拟仿真：从"判分器"到"语义干预实验台"

**直觉**：如果只想测"模型怕不怕换一种说法"，最干净的做法是让世界完全不动，只把指令换掉。真机做不到（状态会漂），普通数据集也做不到（每条演示只配一句话）；只有仿真能逐帧冻结状态、重放同一条动作，再替换 `language`。所以仿真这轮的新身份是**反事实语言干预台**：它不只回答"这个动作值多少分"，还回答"这句话到底指哪个任务"。

**定义（仿真语义）**：设仿真器为 `G`，任务语义程序为 `s`，`E_G(s) → (τ, z)` 返回执行轨迹与计分步向量 `z ∈ {0,1}^m`。称 `s` 在 `G` 中**语义可执行**，当且仅当 `z` 与任务模板的计分步序列一致。语言 `l` 的仿真语义为 `[[l]]_G = { s : C(l)=s 且 s 在 G 中语义可执行 }`。注意这里执行的是**脚本化技能/特权控制器**，不是被评测的学习策略——否则"策略不会做"会被误判成"语言理解错"。

### 2.2 多语言支持：不变量是语义，不是词面

**直觉**：评测给一条字符串，模型不该因为"put/place/set"或"中/英"而变化。公开数据已经有 5 条英文改写，说明出题人自己就在做"改写鲁棒性"；多语言只是把这条轴再拉长。真正要学的不是翻译，而是**把任何语言映射到同一个语义程序**。

**定义（语义等价）**：`l ≡_G l′` 当且仅当 `C(l)` 与 `C(l′)` 都通过仿真语义检查，且它们绑定同一组对象/属性、给出同一有序子目标序列。策略的不变性要求是 `π(a|o,l) = π(a|o,l′)`（对所有 `l ≡_G l′`）。若策略构造为 `π(a|o,l) = π(a|o,C(l))`，则不变性由编译器保证；剩余误差只来自编译器。

## 3. 形式化：语言敏感度与不变性目标

- **语义程序** `s = (A, O, R, Π)`：`A` 有序动作原语（pick/place/insert/unscrew/zip/fold/stack/pour…）；`O` 对象槽位（类型、颜色、数量）；`R` 空间/序关系（right-to-left、on、into、matching color）；`Π` 与计分点对齐的有序子目标谓词。
- **编译器** `C_θ: L → S`。对任务 `j` 的公开 5 条改写 `{l_j1..l_j5}`，要求 `C(l_jk)=s_j`（结构化监督）；这是"改写一致性"最直接的监督信号。
- **语言敏感度指数** `LSI = E_{o, (l,l′) 同语义} d(π(o,l), π(o,l′))`，`d` 可用动作 L2 或分布 KL。真机不可测的部分，用 `G` 冻结世界做代理。
- **稳健目标**：`min_π max_{l ∈ Orbit(l_j)} Risk(π,l)`，`Orbit` 由公开改写 × 离线翻译 × 模板改写 × 仿真过滤生成。注意：这不是"评测语言分布已知"的假设，而是把未知分布包在一个**可测的代理轨道**里。
- **训练目标**：`L = L_act + λ L_parse + μ L_inv + ν L_sim`，其中 `L_parse` 为槽位/程序结构损失，`L_inv` 为同语义改写间的动作一致性/KL，`L_sim` 为仿真语义可执行性（不可导时用作过滤/重排）。
- **两种不变式实现**：
  - **强不变式（推荐）**：策略只条件于 `s = C(l)`，`L_inv` 只用于正则化低置信回退路径；
  - **弱不变式（兼容端到端 VLA）**：策略仍条件于原始 `l`，用 `L_inv` 强行拉近同语义改写的表示与动作。

---

## 4. 瓶颈假设（v3）

- **H1（可证伪的门槛）**：现有 VLA 对 5 条公开改写已经存在可测的动作分歧与步骤分方差；若 `LSI` 很小，则整个 L2S 的收益上限很低，应立即止损。**先用 E201 做零成本审计，再决定投入。**
- **H2**：32 任务的计分点本质上是**谓词序列**，因此仿真可以充当"编译是否正确"的裁判——不是判像素成败，而是判"这个程序是否把对象/关系/顺序绑对了"。
- **H3**：多语言评测是**未证实的**；多改写是**已证实的**。方案必须让"多语言"成为可裁剪的保险层，而不是地基。
- **H4**：把语言坍缩成 `s` 后，UIP-01′ 的验证器、UIP-14 的路由、UIP-11 的判分共享同一个语义坐标，跨任务污染与语言漂移同时下降。

---

## 5. 本轮最大风险与押注

**最大风险一句话**：把"多语言"当成已被证实的评测轴去重投入，而公开证据只支持"多改写"；一旦评测只使用英文原句，L2S 的多语言部分就是零收益的保险——所以必须先跑 E201 的零成本语言敏感度审计，再决定是否扩建。

**→ 本轮最值得押注：UIP-16（L2S 语义编译器）× UIP-17（LangDR 语言域随机化）**——它把"指令"从不可控的输入噪声变成可仿真验证、可随机化、可度量的语义程序，既直接服务 v2 的 UIP-01′/09′/11/14，又能在评测语言未知时以低成本兜底。

## 1. 旗舰深潜：UIP-16 · L2S（Language-to-Simulation Compiler）

### 1.1 语义程序 schema

```yaml
task: T06
actions: [pick, place]                    # 有序原语
objects:
  - {slot: b1, attrs: {color: red}}
  - {slot: b2, attrs: {color: green}}
  - {slot: b3, attrs: {color: yellow}}
relations:
  - {type: sequence, order: [b1, b2, b3], direction: right_to_left}
  - {type: on, target: rack}
subgoals:                                  # 与 30/30/40 计分点对齐
  - placed(b1, rack, order=1)
  - placed(b2, rack, order=2)
  - placed(b3, rack, order=3)
```

### 1.2 从 5 条公开改写抽取同一程序（证据）

| 任务 | 5 条改写的词面差异 | 编译出的同一语义程序 | 计分步 |
|---|---|---|---|
| T06 | "Arrange/Line up/Set/Organize/Place" + "from right to left/rightward to leftward" | `SEQUENCE(red, green, yellow; right→left; on=rack)` | 30/30/40 |
| T14 | "Unscrew/Twist off/Remove/Uncap/Twist open" + cap/lid | `UNSCREW(cap); POUR(bottle→container)` | 50/50 |
| T19 | "Straighten/Align/Smooth out/Adjust/Flatten" + pouch/bag + zip/close | `ALIGN(pouch); CLOSE(zipper)` | 50/50 |
| T27 | "Stack/Pile/Layer/Make a stack/Set ... stacked" + red,green,blue | `STACK([red, green, blue])` | 30/30/40 |
| T31 | "Open/Unzip/Pull open" + place/store/gather + "close/zip" | `OPEN(zipper); PLACE(all stationery); CLOSE(zipper)` | 30/30/40 |

**读表结论**：32 个任务的 5 条改写共享一个稳定的**"动作谓词 + 对象槽位 + 关系/顺序 + 计数"**骨架；词面变化主要发生在动词同义词、容器同义词与介词短语。因此"把改写归一成程序"不是玄学，而是有限槽位的结构化预测。

### 1.3 编译 + 仿真验证伪代码

```python
@dataclass
class TaskProgram:
    task_id: str
    actions: list[str]          # ordered primitives
    objects: list[ObjSlot]      # type / color / count
    relations: list[RelSlot]    # direction / order / receptacle
    subgoals: list[Predicate]   # aligned to scoring points

def compile_verify(lang, task_hint, C, G, tmpl):
    cand = C(lang)                       # slots + confidence; may be a distribution
    if cand is None or cand.conf < THR:
        cand = nearest_canonical(task_hint, lang)   # cross-lingual embedding fallback
    s = bind_slots(cand, tmpl[task_hint])           # fill defaults; resolve aliases
    if not G.objects_realizable(s.objects):         # colors/count/positions exist
        return None
    tau, z = G.execute_program(s)                   # SCRIPTED controller, not the learned policy
    if z != tmpl[task_hint].score_vector:           # ordered predicate satisfaction
        return None                                  # semantic parse failed the sim check
    return s, tau
```

**关键设计**：`G.execute_program` 使用**脚本化技能/特权控制器**执行候选程序。若用学习策略执行，就会把"策略能力不足"和"语言解析错误"混在一起；脚本化执行把二者解耦，使仿真成为真正的语义裁判。

### 1.4 与 v2 的关系

- **供给 UIP-01′**：滚动验证器的当前子目标 `g` 从"手工写死的步骤"变为"`s.subgoals[g]`"，且由计分点直接生成。
- **供给 UIP-14**：技能图路由键从 `observation.language` 原始字符串变为 `s`，路由错误的跨任务污染下降。
- **复用 UIP-11**：GSO 从"给策略 rollout 打分"扩展为"给**任意程序**做可执行性验证"。

## 2. UIP-17 · LangDR（Language / Paraphrase Domain Randomization）

### 2.1 语言轨道生成

```python
def language_orbit(task, K, C, G, tmpl):
    seeds = public_paraphrases[task]                 # 5 English (verified 2026-11-13)
    translated = [translate(x, lg) for x in seeds for lg in LANGS]   # offline only
    templated  = template_paraphrases(task)          # slot substitution + synonym swap
    noisy      = [add_distractor(x) for x in templated]  # e.g. "it is raining, but ..."
    orbit = seeds + translated + templated + noisy
    return [x for x in orbit if compile_verify(x, task, C, G, tmpl) is not None]
```

**三条纪律**：① 翻译只发生在**离线数据工厂**，推理路径不调用外部翻译模型（规避"非单模型"判定）；② 每条候选必须过 `compile_verify`，语义不对的改写不进训练集；③ 语言轨道的主要用途是**正则化与度量**，不是无脑扩数据。

### 2.2 不变性训练（强/弱两种）

```python
# 强不变式：策略只吃语义程序 s = C(l)
loss = L_act(policy(o, C(l)), a_star) + lam * L_parse(C(l), s_task)

# 弱不变式：端到端 VLA 保留原始 l，额外拉近同语义改写
for (o, a_star, langs) in batch:            # langs 属于同一 task
    for l in langs:
        loss += L_act(policy(o, l), a_star)
    loss += mu * pairwise_consistency([policy.encode(o, l) for l in langs])
```

**为什么强不变式优先**：一旦条件于 `s`，同一语义下不同语言/改写的动作**按构造相同**，剩余风险只剩编译器误差；弱不变式只能"尽量拉近"，无法给保证。

## 3. UIP-18 · SIV（Language Sensitivity Index 审计与护栏）

### 3.1 反事实语言干预

```python
def lsi(policy, G, tasks, paraphrases):
    scores = []
    for task in tasks:
        for o in G.freeze_states(task):          # 同一帧 / 同一动作轨迹
            acts = [policy(o, l) for l in paraphrases[task]]
            scores.append(mean_pairwise_dist(acts))
    return mean(scores)
```

- **E201 就是它的最小实现**：不改模型、不训练，只拿 5 条公开改写在同一批冻结观测上跑一遍，测动作分歧与 GSO 步骤分方差。
- **护栏**：当 `C(l)` 置信度低时，回退到"最近规范程序"或"多改写一致性投票"；若投票不收敛，则使用保守的通用技能，而不是赌一个错误程序。
- **在线成本**：确定性解析 + 共享编码器，目标额外延迟 < 5 ms；不引入第二个推理模型。

## 4. UIP-13′ · GTO/BSS（修正 v2 的协议错误）

- **错误**：v2 写"metadata 只握手一次——采用全局最大 k，实际每次可返回 ≤k 步的块"。README §3 明确每个动作数组形状必须恰为 `(T_a, …)`，返回更短块是形状违约。
- **修正 GTO（Global T_a Offline selection）**：`T_a` 是**全局一次性设计变量**。用离线 GSO/真机小样本，在"重观测频率 vs 往返延迟/带宽"之间做一次鲁棒选型：`T_a* = argmin_{T_a} max_{task} Risk(task, T_a)`。
- **修正 BSS（Block Self-Stabilization）**：既然块内不能重观测，就让**块内动作自稳、块尾保守**：接触密集阶段（插入/合盖/拉链）把块尾若干步收缩为"保持/微调/回撤"安全动作；把真正的"高价值核验"留给下一次 `get_action` 的第一帧。
- **结论**：实时性不是运行期换块长，而是**离线选一个全局 `T_a` + 块内风险整形 + 下一次观测的验证排序**。

## 7. 合规与风险

- **单模型合规**：`C` 是确定性解析器或共享骨干上的结构化头，属于同一模型；翻译/改写大模型只在**离线数据工厂**使用。若把翻译模型放进推理路径，可能被判为额外模型/非单模型。
- **协议红线**：`T_a` 握手固定、形状恰为 `(T_a,…)`、`observation.language` 偏移必须 `[0]`、每端口状态隔离。
- **误差传播**：`C` 错 → 子目标错 → 验证器把错误当正确。用 UIP-18 的低置信回退 + 仿真验证 + 多改写一致性投票三重护栏。
- **仿真语义 gap**：L2S 只把仿真当"结构/顺序/绑定"裁判，不把像素级接触成败当真；真机锚点仍不可省。
- **证据边界**：主结论只建立在"多改写"上；"多语言"标注为**未证实评测轴**，作为保险而非卖点。

## 9. 本轮最大风险 & 押注

**一句话**：本方案最大的风险是把"多语言"当成已被证实的评测轴，而公开证据只支持"多改写"；一旦评测只用英文原句，多语言投入就是零收益保险——所以 E201 必须作为**上线前的止损闸门**，而不是事后分析。

**→ 押注：UIP-16（L2S）× UIP-17（LangDR）**——用仿真把语言变成可执行、可验证、可随机化的语义程序；它让 v2 的验证/路由/判分共享同一个语义坐标，并在评测语言未知时以确定性解析器 + 离线数据工厂低成本兜底。
