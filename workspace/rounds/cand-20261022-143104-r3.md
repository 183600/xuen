# 想法区 · 第 3 轮（本循环）：从 X-DUB/AG* 到 X-DUB/ACO-D

**灵感词**：蚁群算法 / dependency analysis / algorithmic paradigm  
**起点**：v0.5「X-DUB/AG*」。它已经有一致 A* 的路径最大下界 `F`、focal + 贪心 guide、THRESH、DOM-GEN 和证明 DAG。本轮不推翻这些定理，只追问一个更靠前的问题：**我们为什么默认整张 DAG 是一个不可分的搜索空间？**  
（状态文件里的 v0.5 内部标为第 7 轮；本循环此前两轮被拒，本轮是第 3 次提交，版本号接 v0.5 记为 v0.6。）

## 一句话直觉：分解负责“变小”，蚁群负责“变好”，A* 负责“证完”

v0.5 的搜索是单体式的：一个根，一棵树，一张覆盖全图的证明。它的下界 `L0` 把整张图的 critical path 和总工作量取 max；它的上界来自三条固定的表调度规则；它的证明必须从根一路闭合到叶。

本轮把 **dependency analysis** 放在最前面：先用**串行分解**把 DAG 切成若干块，使整图 OPT 恰好等于各块 OPT 之和；再在每块里用**蚁群**构造可行上界；最后让 v0.5 的 focal A* 只负责给每块发一张局部证书，证书相加即得整图最优性。三个灵感词不是三个补丁，而是三个**不同粒度**的层：

```text
dependency analysis ：把问题切成 OPT 可加的块（结构层）
蚁群算法           ：在块内构造好的可行解（ primal 层）
algorithmic paradigm：Decompose–Construct–Certify（控制层）
```

## 1. 我先看到的三处浪费

### 1.1 下界不会跨阶段相加

v0.5 的 `L0(σ)=max(CP, W/m, ...)` 是**整图**的 max。若 DAG 可以写成两段完全串行的块 `B1 ⊳ B2`，真正的下界应该是 `OPT(B1)+OPT(B2)`，而不是把两段的 critical path 和工作量放在一起取 max。取 max 会把“一段是链、一段是宽并行”的结构平均掉。

最小例子：`B1` 是 4 个 `p=5` 的链（CP=20, W=20），`B2` 是 8 个 `p=5` 的独立任务、m=2（CP=5, W/m=20）。整图 `L0=max(25,20)=25`，但 `OPT=20+20=40`。**L0 丢了 15 个时间单位**，而 `L_SER=L0(B1)+L0(B2)=40` 一步到位。

### 1.2 上界没有记忆

v0.5 的 guide 是 CP/LPT/MWKR 三条固定规则。它们不学习，也不区分“这块是链、那块是宽并行”。同一类 `(任务, 机器)` 决策在不同状态被反复重新构造。蚁群给我的启发不是“再加一条规则”，而是**把信息素放在真正自由的地方**：可比较的任务对是偏序强制的，只有不可比较的任务对才是可交换的决策。于是信息素应该定义在**不可比对**上，而不是整张任务表上。

### 1.3 证明是单体的

v0.5 的证明 DAG 很强，但没有“分块证明、相加即得”的规则。如果 `OPT=Σ OPT_i`，那么每块只需一张局部证书，根证书由 `SERIES-COMPOSE` 组合。这能把一个指数大的证明拆成若干个小证明，也让 checker 可以逐块独立检查。

## 2. dependency analysis：串行前缀与可加分解

固定 DAG `G=(V,E)`、工时 `p`、m 台同构机器。称 `S⊆V` 是一个**串行前缀**，若 `S` 是下闭集（ideal），且每个 `u∈S` 都先于每个 `v∉S`。拓扑序前缀中，只有满足“所有前缀任务都是所有后缀任务的祖先”的那些才是串行前缀。

**分解定理**：若 `V=B1⊳B2⊳...⊳Br`（任意 `i<j`，`Bi` 中每个任务都先于 `Bj` 中每个任务），则

```text
OPT(G) = Σ_i OPT(G[Bi]).
```

证明直觉：任取整图调度，令 `T_i` 为前 i 块全部完成的时间。因为块间完全串行，第 i 块的任务只能在 `[T_{i-1},T_i]` 内跑，且 `T_{i-1}` 时所有机器已空；把这段平移回 0，就是 `G[Bi]` 的一个可行调度，故 `T_i-T_{i-1}≥OPT(Bi)`。相加得下界。反过来，把每块的最优调度首尾相接，块边界天然是机器全空的 barrier，得到上界。证毕。

这个定理有两个直接推论：

1. **加性下界**：`L_SER=Σ L0(Bi)` 可采纳，且 `L_SER≥L0(G)`。因为 `CP(G)=Σ CP(Bi)`（完全串行保证最长路径可拼接）、`W(G)/m=Σ W(Bi)/m`，而 `max(Σa_i,Σb_i)≤Σmax(a_i,b_i)`。
2. **状态级分解**：对任意状态 σ，若剩余 DAG 分解为 `B1⊳...⊳Br`，则
   ```text
   OPT(σ) = OPT(B1; A(σ)) + Σ_{i≥2} OPT(Bi; 0).
   ```
   第一块继承当前机器可用时间；第一块结束后所有机器全空，后续块从零开始。这是本轮最漂亮的结构性质：分解不只发生在根，也可以发生在搜索的任意状态。

**最大分解**：串行前缀对交、对并封闭，所以最小非空串行前缀唯一；贪心地“取当前最小的串行前缀”就得到唯一的**最粗分解**。实现只需拓扑前缀 + 祖先 bitmask，`O(n²)` 次 bit 检查。

我也诚实地记下边界：40 个随机 DAG 里只有 7 个有非平凡串行割（2 个两块，5 个三块以上）。**分解是结构性的，不是普适的。**

## 3. 蚁群：把信息素放在不可比对

对块 `Bi`，先算传递闭包。若 `i≺j` 或 `j≺i`，这一对是强制的；只有不可比较的 `(i,j)` 才是自由顺序。令 `P` 为有序不可比对集合，信息素 `τ_ij` 只定义在 `P` 上。

蚂蚁从当前状态出发，反复在**就绪集 R**（它天然是一个反链）中选任务：

```text
mass(i) = Σ_{j∈R, j≠i} τ_{ji}
Pr(i) ∝ mass(i)^α · (q_i+p_i)^β
```

选完任务后，机器用“最早完成”规则确定性地选：`k*=argmin_k max(A_k, predmax_i)+p_i`。于是一只蚂蚁的基因型是一个**线性扩展**，表现型是一条 list schedule。

更新用 MMAS 风格：先蒸发，再用本次最好（或历史最好）的顺序强化所有不可比对对；搜索中找到更好的 incumbent 时，把已调度任务按完成时间排序（这一定是一个线性扩展），再强化一次。信息素只在 `P` 上，所以链式块 `P=∅` 时蚂蚁没有任何随机性——dependency analysis 直接告诉 ACO“这里没什么可学的”。

## 4. 我原本以为 ACO 应该做 guide，实验打了我一巴掌

最初的假设很自然：v0.5 的 guide 是 CP/LPT/MWKR，ACO 学到的信息素应该给出更好的 focal guide。于是我先实现了 `warm_aco_g`：用 ACO 的构造成本做焦点内排序，但**不让蚂蚁更新 U**。

16 个困难随机实例（n=9–10, m=2，全部用独立 DFS 验证 OPT）上的结果：

```text
warm_greedy（5 只根蚂蚁，greedy guide） : 887 步
warm_aco_g （5 只根蚂蚁，ACO guide）     : 1075 步
```

**ACO 只做 guide 反而更差**，而且因为搜索跑得更久，蚂蚁调用从 0 涨到 29,386 次。真正有效的是另一件事：让蚂蚁**更新 incumbent U**，guide 仍用 greedy：

```text
warm_aco_u（蚂蚁只更新 U，greedy guide） : 328 步
warm_aco  （蚂蚁同时更新 U 和 guide）     : 306 步
```

也就是说，**ACO 的主要贡献是 primal，不是 ordering**。这和 v0.5 的 guide 消融（CP/LPT/MWKR 只差约 5%）是一致的：在廉价特征下，“选哪个节点”不是主要矛盾，“当前有多好的完成值”才是。于是本轮的设计从“ACO-guided search”改成“**ACO-primal + greedy guide + exact certification**”。这是一个负结果带来的修正，不是包装。

## 5. algorithmic paradigm：Construct–Decompose–Certify

三层各司其职：

```text
Decompose ：dependency analysis 找串行割；OPT 可加；L_SER=Σ L0(Bi)
Construct ：ACO 在每块内构造可行调度，更新 U；guide 可选
Certify   ：v0.5 的 focal A* 只做“L_i 抬到 U_i”的局部证明；SERIES-COMPOSE 相加
```

控制层只做一个**性能选择**：这块小就精确 DFS；这块是 critical-path 主导就少跑蚂蚁；这块宽而松就多跑蚂蚁。它**从不改变剪枝规则**，所以任何 controller 都不影响正确性；只影响节点数和 anytime。这一点我会在产物区写成定理，而不是口号。

## 6. 本轮真正立住的命题

1. **分解定理**：`V=B1⊳...⊳Br ⇒ OPT=Σ OPT_i`，并给出 barrier 构造与证明。
2. **加性下界**：`L_SER=Σ L0(Bi)≥L0(G)`，严格例子 25 vs 40；24 个 chain-wide 实例上平均 26.25→31.83，22/24 严格变强，21/24 直接等于 OPT。
3. **ACO 可行性**：每只蚂蚁返回合法调度，故 `U_G≥OPT`；信息素只影响采样，不影响证书。
4. **Primal 消融**：`warm_aco_u` 把 887 步降到 328 步（0.35s），而 `warm_aco_g` 升到 1075 步（2.09s）；ACO 的价值在上界通道。
5. **分解的可扩展性**：6 个 20–40 任务的串行块实例，分块精确求解 6/6 在 0.01s 内闭合；单体搜索 220 步只闭合 2/6，在 n=36/40 的困难例上 U/L 仍为 100/90、124/108。
6. **证明组合**：`SERIES-COMPOSE` 把每块的 `[L_i,U_i]` 相加；checker 独立验证割条件、块证明和可行调度，不信任 ACO/controller。

## 7. 我知道的边界

- 只做了 m=2、n≤40 的合成实例；没有 PSPLIB，没有 m>2 的精确异构装箱。
- 随机 DAG 只有 7/40 触发分解；大多数实例仍是 v0.5 的搜索，收益为 0。
- 困难池是按“greedy 需要 ≥12 步”筛出来的，会放大 ACO primal 的优势；未筛实例上 greedy 经常直接命中 OPT。
- `SERIES-COMPOSE` 的 checker 只设计了规则，没有实现完整对拍。
- controller 的阈值（0.95、8、5–40 只蚂蚁）是手拍的，没有调参。
- 状态级 `DYNAMIC-SERIES` 只有定理，没有单独 benchmark。

## 本轮的一句话最大风险

**当前方案最大的风险是：精确可加分解只在存在完整串行割的 DAG 上触发（随机 DAG 仅 7/40 有非平凡割），在没有这种结构的 wide/precedence-heavy 实例上，ACO 只能降低 U、不能降低 L，算法仍退化为 v0.5 的指数搜索；dependency analysis 给的是结构性收益，不是普适加速。**

## 0. 版本关系与本轮增量

v0.5（X-DUB/AG*）已经建立：

- `P|prec|Cmax` 的 `(任务,机器)` 动作空间与最优性覆盖；
- 一致 A*：`F(σ)=max(F(parent),L_loc(σ))`，`f(σ)=max(C(σ),F(σ))`；
- FOCAL-GREEDY：在 `f` 的容许带内用贪心完成做 guide；
- THRESH-CERT、CERT-INHERIT、DOM-GEN 与证明 DAG；
- 组合下界 `L_X5=max(L0,L_D,L_AV,L_TH)`。

v0.6 **不推翻** 其中任何一条定理，只做五处增量：

1. **SERIES-DECOMP**：用 dependency analysis 找串行前缀，把 DAG 切成
   `V=B1⊳B2⊳...⊳Br`；证明 `OPT=Σ OPT_i`。
2. **SERIES-LB**：加性下界 `L_SER=Σ L_i(B_i)`；证明
   `L_SER≥L0`，并给出严格例子。
3. **ACO-PRIMAL**：信息素定义在**不可比对**上；蚂蚁构造线性扩展，
   经 earliest-finish list schedule 解码为可行上界。ACO 主要用于
   更新 `U`，guide 可选且默认关闭。
4. **CDC-CONTROLLER**：Construct–Decompose–Certify 三层；按块的
   规模、自由度和 criticality 分配预算。controller 只改性能，不改正确性。
5. **SERIES-COMPOSE**：证明 DAG 新增分块组合规则；checker 独立验证
   割条件、块证明和可行调度。

关闭 ACO 和分解，退回 v0.5 的 focal + DOM + inherit；只开分解，
得到“分块精确 + 加性下界”；只开 ACO，得到“v0.5 搜索 + 蚁群 primal”。

```text
L_X6(σ) = max( L_X5(σ), L_SER(σ) )
L_SER(σ) = L_1(B_1; A(σ)) + Σ_{i≥2} L0(B_i; 0)
           （B_1⊳...⊳B_r 是剩余 DAG 的串行分解）
F(σ)    = max over path certificates
f(σ)    = max( C(σ), F(σ) )
U(σ)    = min( U_greedy, U_ACO, U_children )
```

在根上，`L_i(B_i)≥L0(B_i)` 且已证 `L_SER≥L0`，所以 `L_X6≥L_X5`。
注意：`L_SER` 是**整图绝对下界**，不是状态局部量；在状态 σ 上使用时，
它是对剩余 DAG 的分解，且第一块继承 `A(σ)`；与 `L_X5` 取 max 只会更强，
不会破坏可采纳性。

## 1. 问题、符号与复用的旧结论

### 1.1 形式化问题

```text
P | prec | Cmax
```

给定任务集 `V={1,...,n}`、工时 `p_i∈Z_{≥1}`、优先约束 `E⊆V×V`（DAG）、
同构机器数 `m`。调度由开始时间 `s_i` 和机器 `μ_i` 组成，满足：

```text
(i,j) ∈ E  ⇒  s_j ≥ s_i + p_i
μ_i = μ_j  ⇒  [s_i,s_i+p_i) 与 [s_j,s_j+p_j) 不重叠
```

目标 `Cmax=max_i(s_i+p_i)` 最小；最优值记 `OPT`。

### 1.2 符号表（v0.6 新增/重定义）

| 符号 | 含义 |
|---|---|
| `σ=(S,A,c)` | 已调度集、机器可用时间、完成时间 |
| `R=V\S` | 未调度集 |
| `C(σ)=max_k A_k` | 已提交 makespan |
| `OPT(σ)` | 从 σ 出发完成剩余任务的最小绝对 makespan |
| `i≺j` | 传递闭包中的“i 先于 j” |
| `Anc(t)` | t 的全部祖先（含传递） |
| `S` 是 ideal | `v∈S, u≺v ⇒ u∈S` |
| `S` 是串行前缀 | S 是 ideal，且 `∀u∈S, v∉S: u≺v` |
| `B1⊳...⊳Br` | 串行分解：`i<j ⇒ Bi` 中每个任务先于 `Bj` 中每个任务 |
| `L_SER(σ)` | `Σ_i L_i(B_i)`，加性下界 |
| `P` | 有序不可比对集合 `{(i,j): i≠j, ¬(i≺j), ¬(j≺i)}` |
| `τ_ij` | 不可比对 `(i,j)` 上的信息素 |
| `φ` | 自由度 `|P_unordered| / C(n,2)` |
| `w` | 最大反链宽度（Dilworth） |
| `ρcrit` | `L0/U`，critical-path 主导度 |
| `U_G(σ)` | 贪心组合上界 |
| `U_A(σ)` | 蚁群构造上界 |
| `K` | 根/块级蚂蚁数 |
| `K_g` | 每个 focal 候选的蚂蚁数 |
| `n_exact` | 小块直接精确 DFS 的阈值 |
| `CDC` | Construct–Decompose–Certify 范式 |
| `SERIES-COMPOSE` | 证明 DAG 的分块相加规则 |

### 1.3 复用的 v0.5 结论

以下结论直接继承，不再证明：

- **动作覆盖性**：动作 `(i,k)` 在 `t=max(A_k,max_{j∈pred(i)}c_j)` 开始；
  从根出发的某条动作序列可达到一个最优调度。
- **一致 f**：`F` 可采纳，`f` 沿边单调，`h=f-C` 一致；best-first 不需
  reopening。
- **Focal 精确性**：只要剪枝用可采纳的 `f` 和 `f≥U`，焦点内任意 guide
  选择都不破坏精确性。
- **AVAIL/THRESH 可采纳**：装箱不可行意味着不存在 `≤H` 的完成。
- **DOM-GEN**：同 `S` 下若 `A_σ≤A_τ` 且 `c_σ≤c_τ`，则
  `OPT(σ)≤OPT(τ)`。
- **证明树/证明 DAG 的局部检查规则**可靠。

v0.6 只替换/扩展“问题如何分块、上界如何构造、证明如何组合”；动作空间、
`F/f`、focal、DOM、THRESH 的语义保持不变。

## 2. 动机：三个结构性缺口

### 2.1 缺口一：下界不会跨阶段相加

v0.5 的 `L0(σ)` 是整图 `max(CP, W/m, max p)`。若 DAG 是两段完全串行的块，
真正的下界是两块之和，而不是两块的 max。

**例 A（加性缺口）**：

```text
m=2
B1：4 个任务，p=5，成链          CP=20, W=20, L0(B1)=20
B2：8 个独立任务，p=5            CP=5,  W=40, L0(B2)=20
B1⊳B2（B1 每个任务先于 B2 每个任务）
OPT = 20 + 20 = 40
L0(整图) = max(CP=25, W/m=20) = 25
L_SER    = 20 + 20 = 40
```

`L0` 把“链”的 20 和“宽并行”的 20 放进同一个 max，丢了 15。
`L_SER` 把两个不同瓶颈分别保留，再相加。

### 2.2 缺口二：上界没有记忆

v0.5 的 guide 是 CP/LPT/MWKR 三条固定规则。它们：

- 不区分“链式块”和“宽并行块”；
- 不在状态之间共享信息；
- 对同一类 `(任务,机器)` 决策反复从零构造。

ACO 的启发不是“再加一条规则”，而是**把信息素放在真正自由的地方**：
可比较的任务对是偏序强制的，只有不可比较的任务对才是可交换的决策。
在链式块上 `P=∅`，ACO 没有随机性，dependency analysis 直接告诉我们
“这里没有什么可学的”。

### 2.3 缺口三：证明是单体的

v0.5 的根证明必须覆盖整张图。若 `OPT=Σ OPT_i`，每块只需一张局部证书，
根证书由 `SERIES-COMPOSE` 相加。这带来三个好处：

- 证明规模从“整图的指数”变成“各块指数之和”；
- checker 可以逐块独立检查，错误定位到块；
- 块可以并行求解/检查。

### 2.4 三个灵感词的分工

- **dependency analysis**：串行前缀、最大分解、`L_SER`、自由度 `φ`、宽度 `w`。
- **蚁群算法**：不可比对上的信息素、线性扩展构造、primal 上界、
  跨状态信息迁移。
- **algorithmic paradigm**：Construct–Decompose–Certify；按依赖统计量
  选择精确/蚁群/分块；controller 不影响正确性。

## 3. 依赖分析层：串行分解

### 3.1 串行前缀与串行分解

**定义 1（串行前缀）**：`S⊆V` 是串行前缀，若

```text
(1) S 是 ideal：v∈S 且 u≺v ⇒ u∈S；
(2) S 完全先于补集：∀u∈S, ∀v∉S: u≺v。
```

**定义 2（串行分解）**：`V=B1⊔...⊔Br` 是串行分解，若对任意 `i<j`，
`∀u∈Bi, v∈Bj: u≺v`。记 `B1⊳...⊳Br`。

等价地，存在串行前缀链

```text
∅ ⊂ S1 ⊂ S2 ⊂ ... ⊂ Sr=V,   Bi=Si\S_{i-1}.
```

**引理 1（串行前缀的格结构）**：串行前缀对交、对并封闭。

**证明**：

- 并：设 `S,T` 串行。取 `u∈S∪T`，`v∉S∪T`。若 `u∈S`，由 S 串行得
  `u≺v`；若 `u∈T\S`，由 T 串行得 `u≺v`。故 `S∪T` 串行。
- 交：设 `S,T` 串行。取 `u∈S∩T`，`v∉S∩T`。若 `v∉S`，由 S 串行得
  `u≺v`；否则 `v∈S` 且 `v∉T`，由 T 串行得 `u≺v`。故 `S∩T` 串行。
- ideal 对交并显然封闭。证毕。

**推论 1**：最小非空串行前缀唯一；所有串行前缀都是它的迭代并。
因此贪心“每次取当前最小的非空串行前缀”得到唯一的**最粗分解**。

### 3.2 分解定理

**定理 1（OPT 可加）**：若 `V=B1⊳...⊳Br`，则

```text
OPT(G) = Σ_{i=1}^r OPT(G[Bi]).
```

其中 `G[Bi]` 是 `Bi` 的诱导子图，外部前驱在块开始时已经完成。

**证明**：

**下界**。取任意整图可行调度 σ，令 `T_i` 为 `B1∪...∪Bi` 的最大完成时间，
`T_0=0`。因为块间完全串行，任何 `Bi` 任务都不能在 `T_{i-1}` 之前开始；
且 `T_{i-1}` 时 `B1∪...∪B_{i-1}` 已全部完成，所有机器空闲。把 σ 限制在
`Bi` 上并平移到 `[0,T_i-T_{i-1}]`，得到 `G[Bi]` 的一个可行调度
（机器在 `T_{i-1}` 全空，前驱在块内或更早块内，已满足）。因此

```text
T_i - T_{i-1} ≥ OPT(G[Bi]).
```

对 i 求和：

```text
Cmax(σ) = T_r = Σ_i (T_i-T_{i-1}) ≥ Σ_i OPT(G[Bi]).
```

**上界**。对每块取一个最优调度，把 `Bi` 的调度整体平移到
`t_i=Σ_{j<i} OPT(G[Bj])`。块间完全串行保证跨块优先约束成立；块内调度
合法；相邻块在边界 `t_i` 不重叠且所有机器空闲。因此拼接是整图可行调度，
makespan 为 `Σ_i OPT(G[Bi])`。

上下界相等。证毕。

**推论 2（barrier）**：存在一个最优整图调度，它在每个块边界
`t_i=Σ_{j≤i} OPT(G[Bj])` 处所有机器同时空闲。也就是说，块边界是
**无损失的同步屏障**。

### 3.3 最大分解算法

输入：DAG `G`、拓扑序 `π`、祖先 bitmask `Anc(t)`。

```text
SERIES-DECOMP(G,π,Anc)
1  blocks ← []; start ← 0; prefix ← ∅
2  while start < n:
3      for end = start+1 .. n:
4          prefix ← prefix ∪ {π[end-1]}
5          ok ← true
6          for t ∉ prefix:
7              if prefix ⊄ Anc(t): ok ← false; break
8          if ok: found ← end; break
9      blocks.append(π[start:found])
10     start ← found
11 return blocks
```

**正确性**：第 4-8 行检查的正是“prefix 是串行前缀”。由推论 1，第一个
满足的 `end` 给出当前最小串行前缀；循环得到最粗分解。

**复杂度**：祖先闭包 `O(n+m)` 次 bit-OR；扫描 `O(n²)` 次 bit 检查；
用 Python 大整数时约 `O(n³/word)` 位运算。n≤100 时毫秒级。

**实现细节**：

- `Anc(t)` 由拓扑序递推：`Anc(t)=∪_{u∈pred(t)}({u}∪Anc(u))`。
- 检查 `prefix ⊄ Anc(t)` 等价于 `prefix & ~Anc(t) ≠ 0`。
- 分解只依赖 DAG，不依赖 `p`、`m` 或搜索状态。

### 3.4 加性下界

对每块取任意可采纳下界 `L_i(B_i)`（`L0`、`L_D`、`L_AV`、`L_TH` 均可），定义

```text
L_SER(σ) = L_1(B_1; A(σ)) + Σ_{i≥2} L0(B_i; 0).
```

第一块继承当前机器可用时间；后续块从零开始（§3.5 的 barrier 性质）。
在根上 `A(0)=0^m`，退化为 `Σ_i L0(B_i)`。

**定理 2（L_SER 可采纳）**：`L_SER(σ) ≤ OPT(σ)`。

**证明**：由定理 1 的状态版本，`OPT(σ)=OPT(B_1;A(σ))+Σ_{i≥2}OPT(B_i;0)`；
第一块 `L_1(B_1;A(σ))≤OPT(B_1;A(σ))`，后续块 `L0(B_i)≤OPT(B_i;0)`；
求和。证毕。

**定理 3（L_SER 支配 L0，根上）**：若 `A=0^m` 且 `L_i=L0(B_i)`，则
`L_SER ≥ L0(G)`。

**证明**：

- 完全串行保证最长路径可以逐块拼接：
  `CP(G)=Σ_i CP(B_i)`。
- 总工作量可加：`W(G)/m=Σ_i W(B_i)/m`。
- 因此
  ```text
  L0(G) = max(Σ_i CP_i, Σ_i W_i/m)
        ≤ Σ_i max(CP_i, W_i/m)
        = Σ_i L0(B_i) = L_SER.
  ```
  证毕。

**例 A 续**：`L0=25`，`L_SER=40=OPT`。严格性成立。

**注**：若块内再用 THRESH/对偶，`L_SER` 可以更强；只要每块的下界可采纳，
求和仍可采纳。

### 3.5 状态级分解（DYNAMIC-SERIES）

对任意状态 σ，令 `G_σ` 是剩余任务 `R=V\S` 的诱导 DAG。若
`R=B1⊳...⊳Br`，则

```text
OPT(σ) = OPT(B1; A(σ)) + Σ_{i=2}^r OPT(Bi; 0).
```

**证明**：与定理 1 相同，只是第一块从 `A(σ)` 出发；第一块结束后所有机器
空闲，后续块从零开始。证毕。

**用途**：

- 搜索到任意状态时，若剩余 DAG 有串行割，可以只解第一块，后续块直接
  相加；
- 下界为 `L(B1;A(σ))+Σ_{i≥2}L0(Bi)`；
- 这是根级分解的自然递归版本。

**成本**：每个状态 `O(n²)` 位检查；按剩余 mask 缓存。**本轮只实现了
根级分解**；状态级版本作为定理和下一轮工程项，未单独 benchmark。

### 3.6 自由度与宽度

**定义 3（自由度）**：

```text
φ = |{{i,j}: i<j, i 与 j 不可比}| / C(n,2).
```

`φ=0` 当且仅当 DAG 是全序（链）；`φ→1` 表示几乎无约束。

**定义 4（宽度）**：最大反链大小 `w`（Dilworth）。它衡量“同一时刻最多
有多少任务可竞争机器”。

**用途**：

- `φ` 小、`w` 小 ⇒ 搜索分支少，精确/focal 更合适；
- `φ` 大、`w` 大 ⇒ 构造空间大，ACO 的采样更有意义；
- `φ=0` ⇒ ACO 无自由决策，直接链式调度。

本轮 controller 用 `φ` 和 `ρcrit=L0/U`，不用精确 `w`（精确宽度需要
匹配，n≤40 可做，但本轮未接入）。

## 4. 蚁群层：不可比对图上的构造

### 4.1 为什么信息素放在不可比对

给定块 `Bi`。传递闭包把任务对分成两类：

```text
可比较：i≺j 或 j≺i     —— 顺序被偏序强制
不可比较：¬(i≺j) ∧ ¬(j≺i) —— 唯一可自由决定的顺序
```

线性扩展的集合恰好由“如何排列不可比对对”决定。把信息素放在可比较对上
是浪费统计量，也会让“信息素高”与“偏序强制”混淆。因此定义

```text
P = {(i,j): i≠j, i 与 j 不可比}
τ: P → [τ_min, τ_max],  初始 τ_ij=1.
```

`τ_ij` 与 `τ_ji` 独立；更新时只强化实际顺序。

### 4.2 构造过程

从状态 `(S,A,c)` 出发：

```text
ACO-CONSTRUCT(σ, τ, α, β)
1  S'←S; A'←A; c'←c; order←[]
2  while R'=V\S' ≠ ∅:
3      Ready ← {i∈R': pred(i)⊆S'}
4      for i∈Ready:
5          mass(i) ← Σ_{j∈Ready, j≠i} τ_ji
6          η(i)    ← q_i + p_i
7          w(i)    ← mass(i)^α · η(i)^β
8      i ← sample(Ready, w)
9      base ← max_{j∈pred(i)} c'_j
10     k* ← argmin_k max(A'_k, base) + p_i
11     s ← max(A'_{k*}, base)
12     A'_{k*} ← s+p_i;  c'_i ← s+p_i;  S'←S'∪{i};  order.append(i)
13 return max(A'), order
```

**关键点**：

- `Ready` 天然是一个反链（若 `i≺j`，j 不可能同时就绪），所以第 5 行的
  所有 `(j,i)` 都在 `P` 中。
- 机器分配是确定性的 earliest-finish；一只蚂蚁的基因型就是一个线性扩展，
  表现型是一条 list schedule。
- `η(i)=q_i+p_i` 是剩余 critical path，给蚁群一个“关键路径偏置”；
  `α=1, β=1.4` 是本轮实现值，未调参。

### 4.3 信息素更新

采用 MMAS 风格：

```text
τ_ij ← clamp((1-ρ)·τ_ij, τ_min, τ_max)        ∀(i,j)∈P
for (i,j) in best_order, i before j:
    τ_ij ← clamp(τ_ij + ρ·Δ, τ_min, τ_max)
Δ = 1 + max(0, (U_ref - C_best)/U_ref)
```

本轮参数：`ρ=0.2`，`τ_min=0.05`，`τ_max=6`，`U_ref` 是当前最好上界。

**两种强化来源**：

1. **块级 ACO 阶段**：根/块开始时跑 `K` 只蚂蚁，取最好顺序强化；
2. **搜索 incumbent**：每当 `U` 改进，把已调度任务按完成时间排序
   （这一定是一个线性扩展），再强化一次。

第二种让信息素在搜索过程中持续学习，但**只影响后续采样**，不影响证书。

### 4.4 可行性、上界与搜索空间

**引理 2（蚂蚁可行）**：`ACO-CONSTRUCT` 返回的 `(s,μ)` 是从 σ 出发的
合法完成，`Cmax` 是 `OPT(σ)` 的可行上界。

**证明**：每步只选就绪任务，开始时间不早于所有前驱完成时间和机器可用
时间；同一机器上的任务串行；每个任务恰好调度一次。因此合法。
任何合法调度的 makespan 不小于 `OPT(σ)`，所以返回值 `≥OPT(σ)`。证毕。

**备注（list-scheduling dominance，非正确性所需）**：对 `P|prec|Cmax`，
存在一个最优的 non-delay 调度；把任务按开始时间排序后用 earliest-start
list scheduling 解码，不会比原调度更差。因此“线性扩展 + earliest-finish
解码”的搜索空间在原则上包含一个最优解。这个备注只用于解释 ACO 的
基因型选择，**不用于证明正确性**；即使 dominance 有边界条件，ACO 也只
提供可行上界，证书仍由精确搜索给出。

### 4.5 跨状态构造

`ACO-CONSTRUCT` 接受任意 `(S,A,c)`，不要求从根开始。于是：

- 同一个信息素矩阵可以在搜索的任意状态复用；
- 已调度任务对的 `τ` 被忽略，剩余就绪集的 `τ_ji` 仍有效；
- 这把 ACO 从“根上的多起点构造”变成“每个 focal 候选的快速 primal 评估”。

**注意**：跨状态复用是**启发式迁移**，没有可采纳性保证；它只影响 `U`
和排序，不影响 `L`。

### 4.6 复杂度

- 单只蚂蚁：每步计算 `mass(i)` 为 `O(|Ready|²)`，共 `n` 步，
  朴素 `O(n³)`；用前缀和/稀疏 `P` 可降到 `O(n²+|P|)`。
- `K` 只蚂蚁：`O(K·n³)` 朴素。
- 信息素矩阵：`O(n²)` 空间。
- 本轮 n≤40，朴素实现足够；n≥100 需要增量 ready 集和稀疏更新。

## 5. 认证层：ACO 只做 primal，focal 只做证明

### 5.1 一致 f 的复用

沿用 v0.5：

```text
L_loc(σ) = max( L0(σ), L_D(σ), L_AV(σ;U-1), L_TH(σ) )
F(σ)     = max( F(parent), L_loc(σ) )
f(σ)     = max( C(σ), F(σ) )
```

`F` 可采纳、`f` 沿边单调、`h=f-C` 一致。v0.6 只在**组合下界**里加入
`L_SER`（若状态可分解），不改变这些性质：

```text
L_X6(σ) = max( L_X5(σ), L_SER(σ) )
F(σ)    = max( F(parent), L_X6(σ) )
```

### 5.2 ACO-PRIMAL：上界通道

对 focal 候选 `v`，运行 `K_g` 只蚂蚁：

```text
U_A(v) = min over K_g constructions Cmax
U ← min(U, U_A(v))
```

`U_A(v)` 是可行上界，**只用于更新 U 和可选 guide**。它从不进入剪枝。

**为什么这是主通道**：v0.5 的 guide 消融已经显示 CP/LPT/MWKR 只差约 5%；
本轮的 `warm_aco_g` 实验进一步显示“只用 ACO 做 guide”会把 887 步变成
1075 步。真正有效的是让蚂蚁把 `U` 打下来：`warm_aco_u` 把 887 步降到
328 步，时间从 1.09s 降到 0.35s。

### 5.3 Focal 选择：guide 可选

```text
f_min = min_{v∈Open} f(v)
Φ_ω   = {v∈Open: f(v) ≤ f_min+ω}
v*    = argmin_{v∈Φ_ω, |Φ|≤B_focal} Ĝ(v)
```

`Ĝ(v)` 有三种模式：

```text
GREEDY : min_{π∈{CP,LPT,MWKR}} Cmax(Greedy(v,π))
ACO    : U_A(v)（K_g 只蚂蚁的最好值）
BOTH   : min(GREEDY, ACO)
```

**默认推荐**：`GREEDY`（即 `ACO_GUIDE=False`）。理由：实验显示 ACO guide
单独更差、成本更高；ACO 的边际价值在 primal。`BOTH` 在 16 个实例上
304 步，和 `ACO-PRIMAL + GREEDY` 的 328 步相差约 7%，在噪声范围内；
默认选更便宜、更稳的 GREEDY。

### 5.4 安全定理

**定理 4（guide/primal 不影响正确性）**：把 `Ĝ` 换成任意函数、把
`U_A` 换成任意可行上界，只要：

```text
(1) 剪枝只用 f(v)≥U、L_loc(v)≥U、DOM、证书；
(2) U 始终来自可行调度；
```

则算法返回的 `U` 仍是可行上界，终止时 `U=OPT`。

**证明**：剪枝谓词不依赖 `Ĝ`；`U` 只通过可行调度下降，故始终 `≥OPT`。
由 v0.5 的 focal 精确性，焦点内任意顺序都不丢最优解；由动作覆盖性和
前沿覆盖性，`Open` 耗尽或 `f_min≥U` 时不存在 `Cmax<U` 的完成。
结合 `U≥OPT`，得 `U=OPT`。证毕。

**推论 3**：ACO 的 `α,β,ρ,K`、guide 模式、controller 阈值都可以任意选，
不影响正确性；它们只改变节点数、时间和 anytime。

## 6. CDC 范式：Construct–Decompose–Certify

### 6.1 三层与职责

| 层 | 输入 | 输出 | 是否影响正确性 |
|---|---|---|---|
| Decompose | DAG、拓扑、祖先 | 串行块、`L_SER`、`φ` | 是（割条件必须真） |
| Construct | 块、状态、信息素 | 可行 `U`、可选 guide | 否（只要可行） |
| Certify | `f`、DOM、THRESH、块证明 | `L`、证明 DAG | 是（规则必须可靠） |

**范式一句话**：

```text
Decompose 把问题变小；
Construct 把上界变好；
Certify 把下界证完。
```

### 6.2 依赖统计量与 regime map

对每个块计算：

```text
n_b    = 块大小
φ_b    = 不可比对比例
ρ_b    = L0(B_b) / U_b
gap_b  = U_b - L_b
```

**Controller（启发式，不是定理）**：

```text
if n_b ≤ n_exact:                 EXACT-DFS
elif ρ_b ≥ 0.95:                  FOCAL-GREEDY, K=2（critical-path 主导）
elif φ_b ≥ 0.40 and gap_b ≥ 2:    ACO-PRIMAL, K=clip(8·φ_b·gap_b/L_b, 5, 40)
else:                             FOCAL-GREEDY, K=5
```

本轮实现值：`n_exact=8`，`α=1`，`β=1.4`，`ρ=0.2`，`K_g=2`，
`B_focal=16`，`ω=2`。

**Regime 表**（定性）：

| 结构 | 统计量 | 主导范式 |
|---|---|---|
| 全序链 | `φ=0`, `r=n` | 分解 + 强制调度 |
| 串行块 | `r>1` | Decompose；块内再选 |
| fork-join | `r=3`，中间块宽 | Decompose + ACO 中间块 |
| 宽独立块 | `r=1`, `φ→1`, `ρ` 低 | ACO primal + 精确证书 |
| critical-path 主导 | `r=1`, `φ` 低, `ρ→1` | focal A*，少跑蚂蚁 |
| 随机小 DAG | 多数 `r=1`, `φ≈0.56` | focal + DOM；分解少触发 |

### 6.3 Controller 不变量

**定理 5（controller 无关正确性）**：任意 controller（包括任意阈值、
任意预算、任意 guide 选择）都不改变算法的正确性；它只改变搜索顺序、
节点数和 anytime。

**证明**：controller 的输出只被用于：

1. 选择串行分块（checker 会独立验证割条件，假割会被拒）；
2. 选择 ACO 蚂蚁数（只产生可行 `U`）；
3. 选择 guide（只排序）；
4. 选择 exact/focal（两者都是精确搜索）。

这四者都不改变剪枝谓词的可靠性。由定理 4 和 v0.5 的精确性，结论成立。
证毕。

**意义**：这把“算法范式选择”从 correctness 问题降为 performance 问题；
我们可以安全地按实例结构切换范式，而不需要为每个范式重证正确性。

## 7. 主循环 X-DUB/ACO-D

```text
算法 X-DUB/ACO-D(G,p,m,B)
────────────────────────────────────────────────
1  (π,Anc,q) ← PRECOMPUTE(G,p,m)
2  blocks ← SERIES-DECOMP(G,π,Anc)
3  L ← 0; U ← 0; Proofs ← []
4  for b in blocks:
5      sub ← INDUCED(G,b)
6      (L_b,U_b,proof_b) ← SOLVE-BLOCK(sub,b,B)
7      L ← L + L_b; U ← U + U_b
8      Proofs.append(proof_b)
9  PROOF ← SERIES-COMPOSE(blocks,Proofs,L,U)
10 return U,L,gap=(U-L)/max(1,L),PROOF
```

```text
SOLVE-BLOCK(sub,b,B)
────────────────────────────────────────────────
1  U_b ← CP-LIST(sub)
2  L_b ← L0(sub)
3  if |b| ≤ n_exact:
4      OPT_b ← EXACT-DFS(sub,U_b)       # 独立证书
5      return (OPT_b,OPT_b,BLOCK-OPT)
6  aco ← ACO-INIT(sub)
7  K ← REGIME(|b|,φ_b,L_b/U_b)
8  U_b ← min(U_b, aco.run(K))
9  root ← NEW-NODE(σ0); root.F ← L_b; root.f ← max(C(root),L_b)
10 Open ← {root}; Dom ← {(∅):[(0^m,⊥)]}; L_root ← L_b
11 while Open ≠ ∅ and steps < B:
12     f_min ← min_{v∈Open} f(v)
13     if f_min ≥ U_b: break
14     Φ ← {v∈Open: f(v) ≤ f_min+ω}
15     for v in first B_focal of Φ:
16         g ← GREEDY(v)
17         for _ in 1..K_g:
18             C_a,order ← aco.construct(v)
19             U_b ← min(U_b,C_a)
20             if ACO_GUIDE: g ← min(g,C_a)
21         select v* with min (g,f,id)
22     Open.remove(v*); steps++
23     for w in CHILDREN(v*):
24         if w complete: U_b ← min(U_b,C(w)); continue
25         L_w ← L_LOC(w,U_b)
26         F_w ← max(v*.F,L_w)
27         f_w ← max(C(w),F_w)
28         if f_w ≥ U_b: prune; continue
29         if DOMINATED(w): record; continue
30         Open.push(w); Dom.update(w)
31     if steps mod T_scan = 0:
32         L_root ← THRESH(root,U_b)
33         for v in Open: F(v) ← max(F(v),L_root); f(v) ← ...
34 L_b ← max(L_root, min_{v∈Open} f(v))   # Open 空时 L_b=U_b
35 return (L_b,U_b,BUILD-PROOF-DAG)        # L_b<U_b 时是区间证明
```

**与 v0.5 的差异**：

- 外层多了 `SERIES-DECOMP` 和 `SERIES-COMPOSE`；
- `SOLVE-BLOCK` 里多了 ACO 初始化、`REGIME`、蚂蚁 primal；
- guide 默认 GREEDY，ACO guide 可选；
- `L_b` 的返回在 `Open=∅` 时取 `U_b`（因为所有分支已被 `f≥U` 剪掉）。

**正确性关键**：

- 若预算耗尽且 `L_b<U_b`，返回的是**区间证明**（`SERIES-LB`），
  只声明 `L_b≤OPT≤U_b`，不声明最优；只有 `L_b=U_b` 才是最优性证明。
- `L_b` 只能来自可采纳下界（`L0`、THRESH、对偶、`f`）；
- `U_b` 只能来自可行调度（CP、贪心、ACO、完整子节点）；
- DOM 只在同 `S` 下、且支配者不劣时剪；
- 分块只在 checker 验证割条件后成立。

## 8. 证明 DAG 与 checker

### 8.1 节点类型

在 v0.5 的 `TERMINAL/PRUNED-DUAL/PACK-CORE-AVAIL/THRESH-CORE/INHERIT/
DOMINATED-BY/EXACT/EXHAUSTED` 上新增：

```text
SERIES-DECOMPOSE(blocks, cuts, subproofs)
SERIES-LB(blocks, block_Ls)
DYNAMIC-SERIES(σ, blocks, cuts, subproofs)
ACO-SCHEDULE(order, schedule)
BLOCK-OPT(block, interval [L_i,U_i])
```

- `SERIES-DECOMPOSE`：每块都有 `L_i=U_i=OPT_i`，根 `U=ΣU_i`。
- `SERIES-LB`：只给下界，每块 `L_i≤OPT_i`，根 `L=ΣL_i`。
- `DYNAMIC-SERIES`：状态级分解；第一块用 `A(σ)`，后续用零。
- `ACO-SCHEDULE`：一条可行调度，用来把 `U` 抬到 `Cmax`。
- `BLOCK-OPT`：块的 `[L_i,U_i]` 区间；`L_i` 来自下界证书，`U_i` 来自
  可行调度。

### 8.2 SERIES-COMPOSE 的 checker 规则

```text
CHECK-SERIES(v):
1  验证 blocks 是 V 的划分
2  从原 DAG 重算 Anc（不信任搜索器缓存）
3  for i=1..r-1:
4      S_i ← B_1∪...∪B_i
5      for u∈S_i, t∉S_i:
6          if u∉Anc(t): reject        # 割条件
7  for i=1..r:
8      (l_i,u_i) ← CHECK(subproof_i)
9      验证 l_i ≤ u_i
10     验证 u_i 附带调度可行，Cmax=u_i
11 验证 L = Σ l_i, U = Σ u_i
12 if L = U: accept (OPT=U)
13 else if L ≤ U: accept as interval
14 else reject
```

**独立性**：

- `Anc` 由 checker 从原 DAG 重算；
- 块划分、割条件逐项验证；
- 每块的 `l_i`/`u_i` 由子证明给出，checker 不信任搜索器的 `L_b/U_b`；
- ACO 的顺序、信息素、controller 都不在证明里；只检查最终调度可行。

### 8.3 DYNAMIC-SERIES 的 checker 规则

```text
CHECK-DYNAMIC(v):
1  验证 blocks 是 R(σ) 的划分
2  在剩余 DAG 上重算 Anc，验证割条件
3  第一块：CHECK(subproof_1) 使用 A(σ)
4  后续块：CHECK(subproof_i) 使用 0^m
5  验证 OPT(σ) = u_1 + Σ_{i≥2} u_i
6  验证 L(σ) = l_1 + Σ_{i≥2} l_i
```

**注意**：第一块的 `u_1` 是绝对完成时间（含当前 `A`），后续块的 `u_i`
是相对 makespan；checker 必须按同一时间轴解释。实现时把第一块的调度
平移到 `C(σ)` 之后，后续块依次平移。

### 8.4 可靠性

**定理 6（证明 DAG 可靠）**：若 `CHECK(root)` 通过且返回 `L=U`，则
`U=OPT`。

**证明**：对证明 DAG 做拓扑归纳。

- `TERMINAL/PRUNED-DUAL/PACK-CORE-AVAIL/THRESH-CORE/INHERIT/
  DOMINATED-BY/EXACT/EXHAUSTED`：v0.5 已证。
- `ACO-SCHEDULE`：checker 验证调度可行，故 `OPT≤Cmax=U`。
- `BLOCK-OPT`：`L_i` 来自可采纳下界（归纳），`U_i` 来自可行调度
  （归纳），故 `L_i≤OPT_i≤U_i`。
- `SERIES-DECOMPOSE`：checker 验证割条件，定理 1 给出
  `OPT=ΣOPT_i`；每块 `L_i=U_i=OPT_i`，故根 `L=U=OPT`。
- `SERIES-LB`：定理 2 给出 `L=ΣL_i≤ΣOPT_i=OPT`。
- `DYNAMIC-SERIES`：§3.5 的公式；归纳。
- 区间情形：所有规则保持 `L≤OPT≤U`；根相等时 `U=OPT`。

证毕。

### 8.5 与 v0.5 证明系统的关系

- v0.5 的 `TERMINAL/PRUNED/EXACT/...` 仍是块内证明的叶子；
- v0.6 新增的只是“块间组合”；
- 若 `r=1`，`SERIES-COMPOSE` 退化为单块，等价于 v0.5 的根证明；
- 因此 v0.6 的证明系统是 v0.5 的**保守扩展**。

### 定理 7（任意时刻区间）

在算法运行的任意时刻，

```text
L ≤ OPT ≤ U.
```

**证明**：

- `U` 来自 CP/贪心/ACO/完整子节点，都是可行调度，故 `OPT≤U`。
- `L=ΣL_i`，每块 `L_i` 是可采纳下界，由定理 2 得 `L≤ΣOPT_i=OPT`；
  若还取前沿 `min f`，由 v0.5 的前沿覆盖性也得 `≤OPT`。
- 分块情形由定理 1 保证 `OPT=ΣOPT_i`。

证毕。

### 定理 8（终止即最优）

若算法因 `Open=∅` 或 `L≥U` 终止，则 `U=OPT`。

**证明**：若存在 `Cmax<U` 的完成，由动作覆盖性和前沿覆盖性，它必须经过
某个开节点 `v`，且 `f(v)≤Cmax<U`；这与 `Open=∅` 或 `min f≥U` 矛盾。
结合 `U≥OPT`，得 `U=OPT`。证毕。

### 定理 9（有限完备性）

搜索树有限；每次展开前进一个任务；DOM/证书只删除没有更优完成的状态；
预算无限时前沿最终为空或 `f_min≥U`。最坏时间复杂度仍指数；这是 NP-hard
问题的预期行为。

F_v0.6(σ) ≥ F_v0.5(σ)
f_v0.6(σ) ≥ f_v0.5(σ)

只开 ACO，得到 v0.5 + 蚁群 primal。

## 10. 复杂度分析

### 10.1 单次操作

- **预处理**：拓扑 + 祖先闭包 + `q`，`O(n+m)` 次 bit-OR。
- **SERIES-DECOMP**：`O(n²)` 次 bit 检查；大整数下 `O(n³/word)` 位运算。
- **块诱导**：`O(n_b+m_b)`。
- **L0**：`O(n_b+m_b)`。
- **AVAIL/THRESH**：`O(W log(U-L) T_BP)`，`W=O(n²)`；只在根/周期启用。
- **单只蚂蚁**：`O(n³)` 朴素；稀疏 `P` + 增量 ready 可到 `O(n²+|P|)`。
- **ACO 阶段**：`O(K·n³)`。
- **focal 选择**：扫描 `O(|Open|)`；guide 最多 `B_focal` 次，
  `O(B_focal·(T_G + K_g·n³))`。
- **DOM 检查**：`O(|D_S|(n+m))`，受 `K_dom` 限制。
- **证明检查**：`O(N_proof+|E_proof|+n²)`。

### 10.2 总复杂度

设 `N` 为物化节点数、`B` 为预算、`b_max` 为最大块大小：

```text
时间: O( n³/word + Σ_b [ N_b·(T_L0 + T_AVAIL + T_G)
        + B·K_g·T_ant + N_b·K_dom·(n+m) ] + T_TH )
空间: O( n² + Σ_b N_b(n_b+m) + N_proof )
```

最坏情况：

```text
N_b = O((m·n_b)^{n_b})      若块内无分解
总最坏 = O(Σ_b (m·n_b)^{n_b})
```

- 若 `r=1`，与 v0.5 相同；
- 若所有块都是小链，`b_max=1`，线性；
- 若块是 fork-join 的宽中间块，`b_max` 仍可能很大，指数保留。

### 10.3 成本控制

- ACO 只在根/块开始和 focal 候选上跑，`K`、`K_g` 有上限；
- 分解只在根（本轮）和可选的状态级缓存上跑；
- THRESH 只在根/`T_scan` 周期；
- DOM 表按 `S` 分桶，`K_dom` 截断；
- 证明 DAG 只在终止时构造。

## 11. 实验设计与本轮结果

### 11.1 设置

- **实例**：随机 DAG（边 `i<j` 以概率 `ep` 加入；`p_i` 均匀 `1..pmax`；
  `m=2`）；chain-wide、fork-join、series-of-blocks 三种结构化实例。
- **精确 OPT**：独立 DFS，带 `L0` 剪枝，不使用 ACO/DOM/分解；用于小实例
  对拍。
- **搜索**：v0.5 的 focal + DOM + inherit + 根 THRESH；
  `ω=2`，`B_focal=16`，`K_dom=80`。
- **ACO**：`α=1`，`β=1.4`，`ρ=0.2`，`K=20`（根/块），`K_g=2`（候选），
  `τ∈[0.05,6]`。
- **环境**：Python 3.12，单线程，单次测量；时间只用于相对 sanity check。
- **代码/数据**：`exp/exp_aco.py`（实验）、`exp/results_aco.json`（聚合结果，
  含 `decomp_checks` 的 40 个等价性对拍）、`exp/run_aco.log`（完整日志）。

### 11.2 分解的触发率与等价性

**随机 DAG（n=9–12，40 个）**：

| 块数 | 实例数 |
|---|---:|
| `r=1`（无分解） | 33 |
| `r=2` | 2 |
| `r≥3` | 5 |

平均自由度 `φ=0.558`。也就是说，随机 DAG 只有 **17.5%** 有非平凡串行割；
大多数实例上分解不发生，算法退回 v0.5。

**等价性对拍**：

| 家族 | 实例数 | `Σ OPT(Bi)=OPT(G)` |
|---|---:|---:|
| chain-wide | 20 | 20/20 |
| fork-join | 10 | 10/10 |
| 随机 DAG（非平凡割） | 10 | 10/10 |
| **合计** | **40** | **40/40** |

- chain-wide 的每个实例分解成若干单任务块 + 一个宽块；
- fork-join 全部是 `[1, n-2, 1]`（source、分支、sink）；
- 随机 DAG 的 10 个非平凡实例（从 190 个候选中筛出）也全部满足加性等式；
  这 10 个是“有割”的条件子集，不能用来估计触发率。

**结论**：分解定理在 40 个独立实例上没有反例；但触发率是结构性的。

### 11.3 加性下界

24 个 chain-wide 实例（`c=3..6` 个链任务，`w=4..8` 个独立任务，m=2）：

| 指标 | 值 |
|---|---:|
| 平均 `L0` | 26.25 |
| 平均 `L_SER` | 31.83 |
| 平均增益 | 5.58 |
| `L_SER>L0` | 22/24 |
| `L_SER=OPT` | 21/24 |
| `L0=OPT` | 2/24 |

**典型行**：

```text
c=4, w=7:  L0=40, L_SER=50, OPT=50
c=3, w=8:  L0=30, L_SER=40, OPT=40
c=6, w=4:  L0=22, L_SER=24, OPT=25
```

**结论**：加性下界在 22/24 上严格强于 `L0`，且 21/24 直接等于 OPT。
这不是“更好的启发式”，而是结构性下界。

### 11.4 ACO 在宽块上的 primal 质量

20 个 `P2||Cmax` 宽块（n=10–14，p∈[1,12]，m=2；精确 OPT 用子集和 bitset）：

| 指标 | greedy 组合 | ACO(30) |
|---|---:|---:|
| 命中 OPT | 17/20 | 20/20 |
| 平均 makespan | 36.50 | 36.35 |
| 平均 OPT | 36.35 | 36.35 |

ACO 在 3 个 greedy 失败的实例上找到 OPT；平均只差 0.15。这个收益不大，
但方向一致：**在宽块、greedy 规则失效时，ACO 的采样能补上最后 1–2 个
时间单位**。

### 11.5 困难随机 DAG 上的 focal/primal 消融

**实例池**：260 个随机 DAG（n=9–10，`ep∈{0.15,...,0.35}`，
`pmax∈{8,10,12,15}`，m=2），用 greedy focal 预算 300 筛出 16 个
`steps∈[12,300)` 的困难实例。所有 16 个用独立 DFS 验证 OPT。

**变体**（共享根 THRESH、DOM、inherit、`ω=2`、`B_focal=16`、预算 800）：

- `best`：纯 best-first；
- `greedy`：focal + greedy guide，无 ACO；
- `warm_greedy`：根 5 只蚂蚁更新 U，greedy guide；
- `warm_aco_u`：根 5 只蚂蚁 + 候选处 `K_g=2` 只蚂蚁**只更新 U**，
  greedy guide（推荐配置）；
- `warm_aco_g`：同上，但蚂蚁**只做 guide**，不更新 U；
- `warm_aco`：蚂蚁同时更新 U 和 guide；
- `warm_both`：greedy + ACO 的 guide 取 min，蚂蚁更新 U；
- `greedy_nodom`：关掉 DOM。

| 变体 | 总扩展 | 时间 (s) | 蚂蚁调用 | `ΣU` |
|---|---:|---:|---:|---:|
| best | 1,528 | 0.52 | 0 | 586 |
| greedy | 972 | 1.22 | 0 | 586 |
| warm_greedy | 887 | 1.09 | 0 | 586 |
| **warm_aco_u** | **328** | **0.35** | 4,424 | 586 |
| warm_aco_g | 1,075 | 2.09 | 29,386 | 586 |
| warm_aco | 306 | 0.34 | 4,372 | 586 |
| warm_both | 304 | 0.35 | 4,750 | 586 |
| greedy_nodom | 2,429 | 2.72 | 0 | 586 |

`ΣOPT=586`，所有变体 `ΣU=586`，即 16/16 返回 OPT。

**三个决定性对比**：

1. **ACO primal 是主收益**：`warm_greedy 887 → warm_aco_u 328`
   （步数 −63%，时间 −68%）。
2. **ACO guide 单独有害**：`warm_aco_g 1,075`，比 `warm_greedy` 多 21%，
   时间多 92%；蚂蚁调用 29,386 次。
3. **ACO guide 叠加在 primal 上收益很小**：`warm_aco 306` 对
   `warm_aco_u 328`，约 7%，在噪声范围内；默认选更便宜的 `warm_aco_u`。

**DOM 消融**：`greedy 972` 对 `greedy_nodom 2,429`，DOM 减少约 60%
扩展。这个结论与 v0.5 一致，v0.6 没有改变它。

### 11.7 可扩展性：串行块

6 个 series-of-blocks 实例（`r` 块 × `b` 任务，块间完全串行，块内随机
DAG，`ep=0.3`，`pmax=10`，m=2）。单体搜索预算 220 次扩展，关闭根 THRESH
以隔离 `L0`；分块精确求解每块。

| 配置 | n | OPT | `L0` | `L_SER` | 单体 U/L（步数，时间） | warm U/L（步数，时间） | 分块时间 |
|---|---:|---:|---:|---:|---|---|---:|
| 4×5 | 20 | 81 | 67 | 76 | 81/73（220, 1.0s） | 81/81（33, 0.2s） | 0.00s |
| 4×5 | 20 | 74 | 72 | 73 | 74/74（162, 0.8s） | 74/74（159, 0.9s） | 0.00s |
| 6×6 | 36 | 152 | 150 | 152 | 152/152（22, 0.3s） | 152/152（22, 0.4s） | 0.00s |
| 6×6 | 36 | 96 | 90 | 96 | 100/90（220, 6.0s） | 99/90（220, 7.2s） | 0.01s |
| 8×5 | 40 | 117 | 108 | 117 | 124/108（220, 7.0s） | 118/109（220, 7.9s） | 0.00s |
| 8×5 | 40 | 118 | 115 | 117 | 123/115（220, 6.5s） | 119/115（220, 8.2s） | 0.00s |

**汇总**：

```text
单体搜索在 220 步内闭合：2/6
warm ACO 在 220 步内闭合：3/6
分块精确求解闭合：6/6，最慢 0.01s
```

**关键行**：

- n=36，OPT=96：单体 220 步后 U/L=100/90，仍差 10；分块 0.01s 闭合。
- n=40，OPT=117：单体 U/L=124/108；warm U/L=118/109；分块 0.00s。
- n=40，OPT=118：单体 U/L=123/115；warm U/L=119/115；分块 0.00s。

**“construct vs certify”**：在 n=36 的另一个实例上，`warm_aco` 在 250 步
内把 U 打到 112=OPT，但 L 只到 106；**ACO 能找到最优，却不能证明最优**。
分块精确求解在 0.00s 内给出 112 的证书。这是本轮最重要的实验观察：

```text
ACO 负责“找到”；
dependency decomposition 负责“证明”；
两者不是同一个瓶颈。
```

### 11.8 负结果与边界

1. **ACO guide 单独有害**：`warm_aco_g` 1,075 步 / 2.09s，比 greedy 差。
   原因：ACO 的采样分布与“哪个节点最接近完成”相关性不够，且每次
   guide 评估要跑蚂蚁，成本高。
2. **分解触发率低**：随机 DAG 33/40 无分解；收益集中在结构化实例。
3. **筛选偏差**：困难池按 greedy 需要 ≥12 步筛出，放大了 ACO primal 的
   优势；未筛实例上 greedy 经常直接命中 OPT。
4. **规模小**：n≤40，m=2；没有 PSPLIB，没有 m>2。
5. **checker 未实现**：`SERIES-COMPOSE` 只有规则和可靠性证明，没有代码对拍。
6. **状态级分解未测**：`DYNAMIC-SERIES` 只有定理。
7. **阈值未调**：`n_exact=8`、`0.95`、`0.40`、`K=5..40` 都是手拍的。

## 12. 已知风险

1. **结构性触发风险**：串行割在随机/工业 DAG 上可能很少；没有割时，
   `L_SER=L0`，分解只增加 `O(n²)` 预处理，收益为 0。缓解：先做
   `SERIES-DECOMP` 的快速检查；无割时直接走 v0.5。

2. **ACO 的收益是 primal，不是 guide**：`warm_aco_g` 的负结果说明，
   把 ACO 当 focal guide 可能更慢。缓解：默认 `ACO_GUIDE=False`；
   只在有证据的宽块上开。

3. **ACO 成本**：单只蚂蚁朴素 `O(n³)`；宽块 n 大时，`K_g=2` × `B_focal=16`
   可能比省下的节点更贵。缓解：增量 ready 集、稀疏信息素、按预算禁用。

4. **块大小仍可能爆炸**：fork-join 的中间块是宽并行，`b_max` 可能很大；
   分解只去掉 source/sink，指数搜索仍在。缓解：中间块用 ACO primal +
   focal；必要时做并行组合的专门算法。

5. **分解定理的前提**：完全串行（每个前块任务先于每个后块任务）是强条件；
   一般的 parallel composition 不可加。缓解：只对验证过的串行前缀使用；
   checker 独立验证割。

6. **同构机器假设**：barrier 论证依赖“块边界所有机器空闲”；非同一机器、
   release time、抢占都会破坏。缓解：明确边界；不要直接套用。

7. **THRESH/A* 的继承风险**：v0.5 的 `L_TH`、DOM、focal 的已知风险仍在；
   特别是 `L_TH` 对 precedence-heavy 间隙几乎无效。

8. **证明 DAG 的工程复杂度**：`SERIES-COMPOSE`/`DYNAMIC-SERIES` 的
   checker 尚未实现；割条件、块时间轴平移、共享子证明都需要仔细处理。
   一个错误的割验证会接受假最优。

9. **状态级分解的开销**：每个状态 `O(n²)` 位检查；若频繁调用，可能
   比省下的节点更贵。缓解：按剩余 mask 缓存，只在根/周期启用。

10. **Controller 阈值**：`0.95`、`0.40`、`n_exact=8`、`K=5..40` 都是
    手拍的；不同分布上可能次优。缓解：controller 不影响正确性；可以
    换成学习/bandit，但先证明相关性。

11. **筛选偏差**：困难池按 greedy 弱筛出，ACO 的优势可能被放大；
    未筛实例上 greedy 经常直接命中 OPT。缓解：报告未筛分布；
    做全池平均而不是只报困难池。

12. **没有跨实例迁移证据**：本轮 ACO 信息素在单实例内学习；没有证明
    “在未见家族上更好”。v0.4 的 bandit 负结果仍然成立。

13. **最坏情况没有改善**：仍是 NP-hard 的指数搜索；分解只把
    `O(2^n)` 变成 `O(Σ2^{b_i})`，没有新的最坏界。

14. **证明规模**：每块的证明 DAG 仍需存储；若块很多，证明节点总数
    可能接近单体。缓解：`SERIES-LB` 只存下界，不存完整块证明；
    只在需要时展开。

---

## 13. 一句话最大风险

**当前方案最大的风险是：精确可加分解只在存在完整串行割的 DAG 上触发
（随机 DAG 仅 7/40 有非平凡割），在没有这种结构的 wide/precedence-heavy
实例上，ACO 只能降低 U、不能降低 L，算法仍退化为 v0.5 的指数搜索；
dependency analysis 给的是结构性收益，不是普适加速。**
