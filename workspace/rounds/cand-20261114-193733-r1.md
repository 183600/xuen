# 第 70 轮（承接第 69 轮「FLUID-RAS」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「痛点分析」×「多模态融合」）

> R69 把闭环从「不确定就收紧」推进到「不确定就去求证」，已经会看、会问、会摸。但它有两块从未被审视的地基：
> 1. **它把「所有不确定性」当成同一种痛。** R69 的触发条件是 `U_epi = H_mode·g(Δ_min)`，交互目标是通用 `VoI`。可在真实部署里，绝大多数动作歧义是**无害的**——两个模态都安全，只差一点效率或风格；真正造成痛的是极少数**尾部事件**：擦碰、掉落、误伤、用户被反复打扰。为一个不改变任何痛点的歧义去提问，不只是浪费预算，还会稀释对真痛点的注意力，并扩大被投毒的面。
> 2. **它把「融合」当成「越多越好」的加权平均。** R69 的 CIA 选「判别力最大的模态对」，但没有问：这些模态对**当前这个痛点**有判别力吗？两个模态可以在无关维度上高度一致，被误当作「互相验证」；也可以在痛点维度上尖锐冲突，却被平均抹平。**没有痛点坐标的融合，只是在制造更多自信。**
>
> 本轮两个灵感正好补上这两块：
> - **痛点分析**：把「痛」变成一等公民——从审计日志、事故与近失事件中建立**痛点图谱**，按严重度×频率排序，用 **CVaR** 而不是期望来度量；只对「会改变痛点后验」的不确定性做交互；用反事实审计闭环验证「提问/融合到底有没有减轻痛」。
> - **多模态融合**：把融合从「全量加权」升级为**按痛点门控 + 冲突感知**——只融合对当前痛点有边际信息的模态；模态冲突时不平均，而是按校准的尾部可靠性做稳健聚合，并把冲突本身登记为候选痛点。
>
> 核心命题：**不确定性只有映射到痛点上才值钱。** R69 的模态熵可以精确分解为 `H(M|o) = I(M;L|o) + H(M|L,o)`：前一项 `U_pain` 才是值得交互的痛点相关信息，后一项 `U_benign` 是与痛点损失条件独立、被认证后应直接忽略的良性歧义。融合按边际痛点信息门控；全局 ECE 门升级为**尾部校准门**；交互决策的目标从 `VoI` 换成 `VoPI`（value of pain-relevant information）。命名 **TRIAGE-RAS**（Tail-Risk-aware Information Attribution and Gated Evidence fusion）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**到底什么在痛，而我的融合是在减轻它，还是只是在制造更多自信**」。

## 0. 直觉与动机

**灵感 1（痛点分析 → 不确定性必须过「痛点筛」）**
直觉：R69 看见模态熵高就想去问，就像医生看见任何异常指标都开全套检查——查得越多，越可能查出无关紧要的「异常」，也越容易被假阳性牵着走。真正的临床思维是先问「这个异常会不会改变治疗决策、会不会伤害病人」。对应到闭环：一个模态分歧只有在**会改变痛点风险**时才值得付交互成本。形式化后这不是启发式，而是一条恒等式：设 `M` 为 R69 的模态身份、`L` 为痛点损失，则
`H(M|o) = I(M;L|o) + H(M|L,o)`。
第二项 `H(M|L,o)` 是「即使已知痛点结果，模态仍不确定」的部分——它对下游损失没有因果作用，去消解它不会降低任何痛。R69 用整个 `H(M)` 触发交互，**系统性地把良性歧义当成了痛点**。

**灵感 2（痛点分析 → 痛有频率、严重度与长尾，期望会骗人）**
直觉：产品里的「痛点排序」很少看平均值，而是看「多久发生一次 × 发生时多疼」，并且对灾难性事件设硬门槛。R69 的期望风险会把一次罕见但致命的擦碰，和一千次轻微的超时平均掉。TRIAGE 因此用 **CVaR**（最坏 `1−α` 尾部的条件期望）度量软痛点，并对灾难性痛点设 `P(p_k) ≤ ε_k` 的**字典序硬约束**：安全先于效率，且这个优先级必须写进证书，不能藏在标量权重里。痛点还分时间尺度——毫秒级碰撞、分钟级任务失败、小时级交互疲劳——需要多尺度聚合，而不是拿同一把尺子量。

**灵感 3（痛点分析 → 痛点是有结构、可归因、会漂移的对象）**
直觉：只把「痛」写成一个标量仍然太粗。工程师做痛点分析的标准五步是：**识别 → 排序 → 归因 → 干预 → 验证**。TRIAGE 逐条落地：痛点图谱（识别）、严重度×频率与 CVaR（排序）、痛点归因头把风险拆到模态与动作（归因）、门控融合/VoPI/尾部校准（干预）、反事实审计与图谱修订（验证）。痛点图谱还是**有版本的**：新事故、新近失、审计发现的未解释残差都会生成候选痛点，而不是让系统永远优化一张过时的清单。

**灵感 4（多模态融合 → 融合要有门，不是所有模态都该说话）**
直觉：多模态融合的常见误区是「先把所有模态拼起来，再让网络自己学权重」。在安全关键场景里这很危险：一个与当前痛点无关的模态（比如背景音乐、桌面纹理）会引入伪相关与多余方差；一个被共同原因污染的模态（反光、共享标定漂移）会和其他模态一起「一致地错」。TRIAGE 的门控不是按「模态通常有多重要」开门，而是按**当前活跃痛点下的边际信息**开门：`Δ_m = I(e_m; L | e_{−m}, o)`。与痛点无关的模态被关掉，既省算力，也减少融合估计的方差；门控还受硬预算 `Σ γ_m ≤ B` 约束，防止「全开最安全」的懒惰解。

**灵感 5（多模态融合 → 冲突不是噪声，是要被解释的信号）**
直觉：两个模态在痛点维度上不一致时，平均（或乘积）会把一个尖锐的矛盾抹成一个看似温和的中庸答案——这恰恰是最危险的。TRIAGE 区分两种融合机制：一致时用 product-of-experts（假设条件独立，融合更锐利）；冲突时切换到稳健混合/中位数式聚合，按各模态**校准后的尾部可靠性**降权，并把这次冲突登记为一个**候选痛点**（fusion-conflict pain point），交给审计与后续交互。冲突不消失，它被记账。

**灵感 6（多模态融合 × 痛点 → 校准必须在痛点上做）**
直觉：R69 的 MCG 用全局 ECE 判断模态权重可不可信。但**全局校准好，不等于尾部校准好**：当痛点事件很稀有（`π_k` 很小），全局 ECE 被绝大多数良性样本主导，一个在痛点上系统性过度自信的模型仍可能拿到漂亮的全局 ECE。TRIAGE 的 TCG 要求 **痛点条件 ECE、CVaR 覆盖率、选择性风险**三项同时过关；任何一项不过，就关闭痛点驱动分诊，退回 R69 的 MCG，再退回 R68。这样 R69 自陈的最大风险（模态分布不可信 → 自信地问错）第一次有了**可测的局部边界**。

**灵感 7（闭环 → 用反事实审计验证「痛有没有真的减轻」）**
直觉：痛点分析的最后一步是验证，而不是上线即结束。每次决策后，用日志里的倾向分数与双重稳健估计，反事实地比较三个策略的痛点：TRIAGE、R69（交互但不分诊）、R68（纯保守）。若 TRIAGE 在某个痛点上反而更差，说明门控/图谱/校准有偏，必须回灌修订。这也是发现「图谱里没有的痛」的唯一系统化通道：**未被解释的残余痛**聚成候选痛点，经人工审核后入谱。

**灵感 8（安全姿态 → 新层必须严格包含旧层）**
直觉：R69 最值得继承的不是某个模块，而是一条理论纪律：新层是旧层的**严格泛化**，不是并列替代。TRIAGE 在「所有结果都是等权痛点、所有模态都痛点相关、尾部校准通过」时，必须逐指令退化为 FLUID-RAS；任何认证失败沿 R69 → R68 单调退避。否则每加一层「痛点/融合」就多一个需要独立信任的黑箱，系统最终会变成一个既会问又会分诊、却没人能证明它安全的怪物。

## 1. 形式化定义（增量：定义 310–327）

**定义 310（TRIAGE-RAS 总览与三不变式）** TRIAGE-RAS = (PPA, PAX, PRU, VoPI, GMF, CAF, TCG, MSA, CPA, RAS-WM†)。三不变式：
(i) **均匀痛点边界**：若痛点图谱覆盖全部结果且损失等权、所有模态的边际痛点信息 `Δ_m > 0`、TCG 通过，则 TRIAGE 逐指令等价于 FLUID-RAS（R69 定义 293）；
(ii) **良性歧义须认证**：被忽略的歧义必须满足 `UCB(I(M;L|o)) ≤ ε_benign` 且以置信度 `1−δ` 成立；认证失败则按痛点相关处理，不得「乐观地忽略」；
(iii) **尾部安全与单调退避**：任何自主/交互决策须通过 TCG 与灾难性痛点约束；不通过则 TRIAGE → FLUID → R68 单调退化，安全侧不弱于 R69。

**定义 311（痛点与痛点图谱 PPA）** 痛点 `p_k = (A_k, L_k, H_k, c_k)`：`A_k` 为触发条件/因果签名，`L_k: Ω → [0, ℓ_max]` 为有界损失，`H_k` 为时间尺度，`c_k ∈ {catastrophic, soft}` 为类别。图谱 `℘ = {(p_k, π_k, ν_k, prov_k)}`，其中 `π_k` 为频率、`ν_k` 为严重度（默认 `CVaR_α(L_k)`）、`prov_k` 为来源溯源（审计/事故/近失/人工）。图谱有版本号 `atlas_ver`；候选痛点需人工审核后才能进入活跃集。活跃集 `℘(o) = {k : P(p_k 可能发生 | o) > 0}`。五步流程固定为：识别（PPA）→ 排序（定义 312）→ 归因（定义 313）→ 干预（定义 316–320）→ 验证（定义 324）。

**定义 312（痛点风险与 CVaR）** 对动作块 `ξ` 与状态 `o`，记痛点损失 `L(ξ,o) = Σ_k 1[p_k] L_k`。期望风险 `R = E[L]`；尾部风险 `CVaR_α(L) = min_τ [ τ + (1/(1−α)) E(L−τ)_+ ]`。灾难性痛点满足 `P(p_k | ξ,o) ≤ ε_k`。分诊目标是一个二元组 `(R, CVaR_α)` 加灾难性约束，而不是单一标量；任何标量化都必须显式给出权重并写入证书。

**定义 313（痛点归因 PAX）** 校准头输出 `q_k(ξ,o) = P(p_k | ξ,o)` 与条件损失分布 `P(L_k | p_k, ξ,o)`；同时给出**模态级归因** `a_{m,k}`：模态 `m` 对 `q_k` 的边际贡献（Shapley 或对模态掩码的积分梯度）。归因有两个用途：监督门控（定义 318）与冲突诊断（定义 320）。归因不是解释性装饰，它决定「关掉哪个模态是安全的」。

**定义 314（痛点相关不确定性 PRU）** 设 `M` 为 R69 的模态身份、`L` 为痛点损失。做精确分解：
`H(M|o) = I(M;L|o) + H(M|L,o)`，
令 `U_pain := I(M;L|o)`、`U_benign := H(M|L,o)`。仅 `U_pain` 进入交互触发与保守收紧；`U_benign` 在通过定义 315 的证书后被忽略。多痛点时令 `L` 为向量并取分诊权重上的上确界 `U_pain = sup_w I(M; wᵀL | o)`，以对权重选择稳健；当 `L` 与 `M` 条件独立时 `U_pain = 0`。

**定义 315（良性歧义证书 BAC）** `BAC(o)=1` 当且仅当存在分布无关的上置信界 `UCB(I(M;L|o)) ≤ ε_benign`（用 MMD/DR 或带保守修正的 bootstrap），且该界在多尺度上一致。BAC 失败时 `U_benign` 被重新归类为 `U_pain`（保守方向）。**BAC 只允许忽略「已证明对痛无因果作用」的歧义，不允许忽略「还没测出作用」的歧义。**

**定义 316（痛点相关信息价值 VoPI）** 对信息动作 `g`（含 R69 的看/问/触，以及本轮的「打开某模态」「换视角/换问法」）：
`VoPI(g) = ρ*(o) − E_{y~p(·|g,o)}[ρ*(o,y)] − c(g)`，
其中 `ρ*` 是在灾难性约束下对 `(R, CVaR_α)` 做字典序优化的最优分诊风险。选 `g* = argmax_g VoPI(g)`，并须通过 R69 的交互预算与 C-RAS-WM 认证。`VoPI ≤ 0` 则不交互，且良性歧义直接忽略。当 `℘` 均匀且 `L` 线性时 `VoPI` 退化为 R69 的 `VoI`；**交互不再是「为了信息」，而是「为了减痛」。**

**定义 317（门控多模态融合 GMF）** 模态 `m ∈ ℳ`（视觉、语言、本体感觉、触觉、听觉、记忆），证据 `e_m = E_m(o_m)`；边际痛点信息 `Δ_m = I(e_m; L | e_{−m}, o)`。门 `γ_m = σ(⟨u_m, φ(℘(o))⟩)`，并受硬预算 `Σ_m γ_m ≤ B` 与硬门 `Δ_m ≤ ε_gate ⇒ γ_m = 0` 双重约束。融合 `z = Σ_m γ_m e_m`（或 product-of-experts）。训练目标 `L_GMF = L_pain + λ I(z; e | L) + μ·compute`，其中信息瓶颈项抑制与痛点无关的伪信息。门是**痛点条件**的：同一模态在碰撞痛点上开、在疲劳痛点上关。

**定义 318（融合经济与风险上界）** 若 `Δ_m ≤ ε`，由 Pinsker 不等式，去掉 `m` 的期望痛点风险增加不超过 `ℓ_max √(ε/2)`。因此门控不是「省算力的赌博」，而是有显式风险预算的近似：`ε_gate` 由 `δ_gate` 反解。低相关模态还会增加有限样本下风险估计的方差（多余维度），所以「少融合」在统计上可能**更准**，不只是一个效率选择。

**定义 319（冲突感知融合 CAF）** 令 `κ` 为各模态痛点预测在痛点相关子空间上的归一化分歧。`κ ≤ τ_conf` 时用 product-of-experts（条件独立、更锐利）；`κ > τ_conf` 时用稳健混合/加权中位数，权重取校准后的尾部可靠性，并把该冲突登记为候选痛点 `p_conf`。**任何情况下不做静默平均。** 门与冲突判定都加滞回（连续 `h` 步才切换），防止抖动。

**定义 320（尾部校准门 TCG）** 全局 ECE 不足以认证尾部。TCG 要求三项同时满足：
(a) **痛点条件 ECE**：对每个活跃痛点，`ECE_k = |conf_k − acc_k|`，并按 `π_k` 加权；
(b) **CVaR 校准**：预测的尾部风险/分位数的经验覆盖率在容差内；
(c) **选择性风险校准**：在给定弃权率 `ρ` 下的实际风险与预测风险一致。
任一项越界则禁用痛点驱动分诊，退回 FLUID（其 MCG 仍可再用），再退回 R68。

**定义 321（痛点感知证据纪律 PED）** R69 的「k 个正交源一致」升级为三条同时满足：
(a) 一致必须发生在**痛点标签** `P` 上，而不是潜在模态 `M` 上；
(b) 一致必须发生在**痛点相关子空间**；在无关维度上的一致不算证据（对手可以零成本伪造）；
(c) 源的有效独立性须可测（残差相关/设计效应 `n_eff`），单源或单次交互永不定案。
系：PED 让「在无关特征上串供」失效，是 R69 引理 18 在痛点坐标下的收紧。

**定义 322（多尺度痛点聚合 MSA）** 每个痛点有尺度 `H_k`。分三层：帧级（ms，碰撞/越界）、回合级（s–min，任务失败/掉落）、部署级（h–day，疲劳/信任侵蚀）。各尺度独立校准、独立门控；聚合为字典序：所有尺度的灾难性约束优先，其次软痛点的 `CVaR_α`。禁止用高频噪声的期望去抵消低频尾部。

**定义 323（分诊策略与优先级）** 给定活跃集 `℘(o)`，按字典序求解：
1) 对灾难性 `k` 满足 `P(p_k) ≤ ε_k`；
2) 最小化软痛点的 `CVaR_α`；
3) 最小化交互/算力成本。
若不可行则弃权/走保守策略，并输出**分诊证书**，明确写出被违反的约束与所用权重。优先级顺序是公开、可审计的，不允许藏在标量损失里。

**定义 324（反事实痛点审计 CPA）** 每次决策记录倾向分数、活跃集、门控、`U_pain/U_benign`、交互与反事实估计。用双重稳健/IPS 估计三策略（TRIAGE、FLUID、R68）在每个痛点上的反事实风险与遗憾 `Regret_k`。反馈两路：
(i) 修订 PPA（修订 `π_k/ν_k`、新增候选痛点、废弃失效痛点）；
(ii) 重校准 TCG 与门控阈值。
未被图谱解释的残余痛做聚类，生成**候选痛点**，经人工审核后入谱——这是处理「未知的痛」的系统化入口。

**定义 325（TRIAGE-AIC 威胁模型）** `ℰ_TRIAGE = ℰ_FLUID × ℰ_pain × ℰ_fusion`：
- `ℰ_pain`：伪造痛点（诱发过度谨慎/反复提问的 DoS）、用干扰项隐藏真痛点、向审计/图谱投毒（删掉某类事故）；
- `ℰ_fusion`：模态捕获（一个模态主导门控、压制诊断模态）、伪相关融合（在无关维度制造一致）、共同原因污染（多模态被同一物理源带偏）；
- 继承 `ℰ_FLUID` 的投毒、幻影模态、ODE 发散。
缓解：图谱溯源与人工复核、门控熵/反捕获正则、冲突证书、PED、TCG，以及「单次证据不定案」。

**定义 326（证书 J_TRIAGE）** `J_TRIAGE = (J_FLUID, atlas_ver, active_set_hash, U_pain, U_benign, BAC, VoPI_ratio, gate_hash, conflict_stats, TCG_report, CPA_regret, triage_ver)`。
`Valid ⇔ Valid(J_FLUID) ∧ (BAC ∨ U_benign 已归入 U_pain) ∧ TCG 通过 ∧ 灾难性约束满足 ∧ 门控预算未越界`。

**定义 327（TRIAGE 闭环主序）** 一个决策周期固定为：痛点识别（PPA/PAX）→ 门控融合（GMF/CAF）→ R69 式多模态采样（FMP/AUD）→ 痛点相关分解（PRU/BAC）→ 尾部校准门（TCG）→ 分诊与交互（VoPI）→ 认证与执行（C-RAS-WM）→ 审计与反事实验证（CPA）。任一环节失败按 TCG → FLUID → R68 单调退避。

class PainAtlas:
    def active(self, o):
        return [k for k in self.points if self.q[k](o) > TAU_ACTIVE]
    def rank(self, k):                      # 严重度 × 频率，灾难性优先
        return (self.points[k].catastrophic, self.pi[k] * self.nu[k])
    def revise(self, cpa_report):           # 只接受有人工复核的候选痛点
        ...

# IP-265 PAX：痛点后验 + CVaR + 模态归因
def pain_risk(modes, o, atlas):
    q  = [atlas.posterior(xi, o) for xi in modes.prototypes]   # P(p_k | xi,o)
    L  = [atlas.loss(qk) for qk in q]
    return expected(L), cvar(L, alpha=0.95), q

# IP-266 PRU：把 R69 的模态熵精确拆成痛点相关 / 良性
def decompose_pain(modes, w, loss_post):
    H_M      = entropy(w)
    U_pain   = mutual_info(mode_identity, loss_post)   # I(M;L|o)
    U_benign = max(0.0, H_M - U_pain)                  # H(M|L,o)
    return U_pain, U_benign

def benign_certificate(U_benign, calib):
    return calib.ucb(U_benign, delta=1e-3) <= EPS_BENIGN   # 定义 315

# IP-267 VoPI：只买“能减痛”的信息
def choose_info(modes, o, atlas, budget):
    rho0 = triage_risk(modes, o, atlas)                    # (R, CVaR)
    best = None
    for g in info_candidates(modes, atlas):                # 看/问/触/开模态/换视角
        if not budget.allow(g) or not c_ras_wm.certify_info(g, o): continue
        rho1 = E_y[triage_risk(bayes_update(modes, y, g), o, atlas)]
        score = pain_gain(rho0, rho1) - cost(g)             # 字典序比较
        if best is None or score > best.score: best = (g, score)
    return best if best and best.score > 0 else None        # 无痛可减 → 不交互

# IP-268/269 GMF + CAF：按痛点门控融合，冲突转稳健聚合
def gated_fusion(obs, active, gates):
    ev = {m: enc[m](obs[m]) for m in obs if gates.delta[m] > EPS_GATE}
    kappa = conflict(ev, active)                           # 痛点子空间分歧
    if kappa <= TAU_CONF:
        z = product_of_experts(ev)                         # 一致 → 锐利融合
    else:
        z = robust_mixture(ev, w=tail_reliability(ev))     # 冲突 → 稳健、不平均
    return z, kappa

# IP-270 TCG：全局 ECE 不够，必须在痛点上校准
def tail_gate(pred, emp, active):
    return (ece_conditional(pred, emp, active) <= TAU_ECE
            and cvar_coverage(pred, emp) <= TAU_CVAR
            and selective_risk(pred, emp) <= TAU_SEL)

# IP-274 主闭环：TRIAGE 插在 R69 的不确定性处置处，反射环不变
def TRIAGE_round(M, obs):
    z, o = M.mtm.forward(...); c, U_cal, thr = M.cof.step(...)
    active = M.ppa.active(o)
    zf, kappa = M.gmf.fuse(obs, active)                    # 痛点门控融合
    if kappa > TAU_CONF: active = active + [M.ppa.conflict_point(obs)]
    K = 1 if M.fmp.mode_head(zf) < TAU_MODE else 4
    samples = M.fmp.sample(zf, K)
    U_ale, U_epi, modes = M.aud.decompose(samples)
    U_pain, U_benign = M.pru.decompose_pain(modes, modes.w, M.pax.loss_posterior)
    bac = M.pru.benign_certificate(U_benign, M.calib)
    if not M.tcg.pass_(M.pax, o, active):                  # 尾部不可信 → 退 R69
        return M.fluid_round(o)                            # FLUID → R68 单调退避
    g = (M.vopi.choose_info(modes, o, M.ppa, M.budget)
         if (U_pain > TAU_PAIN and bac) else None)
    if g is not None:
        answer = M.cia.execute(g); U_pain = M.cia.update_pain(modes, answer)
    # 只对 aleatoric + 未消解的痛点相关不确定性收紧；良性歧义不进 λ
    U_floor = U_ale + (U_pain if g is None else 0.0)
    lam = max(M.efs.risk_scale(...), lam_floor(U_floor))
    k = M.c_ras_wm.certified_prefix(M.ach.propose(...), ..., wm_preds)
    mode = select_mode(modes, U_pain, lam)
    M.cpa.log(o, active, g, U_pain, U_benign, counterfactuals=True)
    return k, lam, mode, (U_pain, U_benign)

## 3. 推导

**引理 19（痛点无关 ⇒ 零信息价值）** 设 `M` 为模态身份、`L` 为痛点损失。恒等式 `H(M|o) = I(M;L|o) + H(M|L,o)` 成立。若 `U_pain = I(M;L|o) = 0`，则 `L ⫫ M | o`，任何信息动作 `g` 对 `L` 的后验不变，故 `VoPI(g) = −c(g) ≤ 0`；一般地，任何信息动作带来的期望痛点下降不超过 `ℓ_max·√(U_pain/2)`（Pinsker）。系：R69 用 `H(M)` 触发交互，其「多问的部分」至多对应 `U_benign`，在 BAC 成立时不产生任何痛点收益。**这就是 R69 过度提问的精确来源。**

**引理 20（全局校准不能证明尾部校准）** 把样本分为痛点区 `A`（概率 `π`）与良性区 `B`（概率 `1−π`），设 `ECE_A = 1`、`ECE_B = 0`。则全局 `ECE = π·1 + (1−π)·0 = π`。取 `π < τ_ece`，全局 ECE 可以任意好，而痛点区校准误差仍为 1。反向有下界 `ECE_A ≥ (ECE_global − (1−π)ECE_B)/π`，当 `π` 很小时该下界几乎不提供信息。系：R69 的 MCG（全局 ECE 门）**不能**守住 R69 自陈的尾部风险；必须用定义 320 的 TCG。

**引理 21（门控融合的痛点风险上界）** 若模态 `m` 的边际痛点信息 `Δ_m = I(e_m; L | e_{−m}, o) ≤ ε`，则由 Pinsker 不等式，去掉 `m` 导致的期望痛点风险增加 `≤ ℓ_max√(ε/2)`。故存在 `ε_gate(δ)` 使门控融合的痛点风险相对全融合增加不超过 `δ`。同时，低相关模态会增加风险估计的有限样本方差；在固定样本预算下，门控版本的风险估计误差不劣于全融合。系：**融合经济性（少算）与统计精度（少噪）可以同时成立**，代价是可显式预算的近似误差。

**定理 18（TRIAGE 对 FLUID 的严格包含）** 在 A99–A101 下：
(i) 当痛点等权且覆盖全部结果、所有 `Δ_m > 0`、TCG 通过时，`U_pain = H(M)`、`U_benign = 0`、全门打开、`VoPI = VoI`，TRIAGE 与 FLUID 逐指令相同；
(ii) 一般情形下，若 BAC 与 TCG 均通过，TRIAGE 的期望痛点风险 `≤ FLUID + δ_gate`（`δ_gate` 由引理 21 给出，`ε_gate → 0` 时严格 `≤`），且交互次数与融合算力不高于 FLUID；
(iii) 若 BAC/TCG/灾难性约束任一失败，TRIAGE 依次退化为 FLUID、R68，故安全侧永不弱于 R68。
**因此 FLUID 是 TRIAGE 在「均匀痛点 + 全相关 + 全开融合」边界上的退化；R68 是再往下的边界。**

**定理 19（尾部安全与单调退避）** 若 TCG 通过且灾难性痛点约束以有效上界执行，则部署策略的尾部风险满足 `CVaR_α ≤ 证书声明值`；BAC 失败、TCG 失败、冲突未消解或交互超时时，策略沿 TRIAGE → FLUID → R68 **单调不降地**退避；所有动作（含信息动作）仍过 C-RAS-WM 认证，故不引入新的物理不安全动作。门控与冲突判定带滞回，交互只改变「用哪个模态/融合」，不改变安全包络 ⇒ 控制连续、无突变。

**推论 19.1（对 R69 最大风险的局部化）** 设 FMP 幻觉出一个模态 `m_halluc`。若它对痛点损失无因果作用（`U_pain` 贡献为 0），由引理 19 它被归入 `U_benign`，BAC 成立时被直接忽略——**幻觉无害**；若它影响痛点，则它抬升 `U_pain`，触发 TCG：尾部校准不过则不提问/不自主执行，校准通过则幻觉被纳入受尾部约束的概率，不能「自信地错到校准界之外」。**R69 的「问错比不问更危险」因此被分解成两个可测条件：痛相关 + 尾部失校准；二者缺一，风险被拦截或证明无害。**

## 6. 本轮最大风险

**一句话**：TRIAGE 的全部收益都押在「痛点图谱是完整且未被污染的」这一前提上——**若某个真实痛点没有被写进图谱（未知的痛）或被人为删掉（图谱投毒），系统会把指向它的歧义认证为「良性」并高效地忽略掉；它不是看错了，而是根本没看——「被证实的良性」会让它连疼都感觉不到**。这正是对 R69「问错比不问更危险」的反面补充：**分诊错了，不问比问更危险。**

**次级风险与缓解**：
1. **尾部数据稀疏**导致 TCG 本身不可信 → 保守先验 + 分层校准 + 不通过即退 R69；
2. **模态捕获**（视觉主导、压制触觉）→ 门控熵/反捕获正则 + 归因审计 + E306；
3. **痛点图谱投毒/DoS** → 来源溯源 + 人工复核 + 伪造痛点检测 + E311；
4. **冲突滞回抖动** → 连续 h 步确认 + 单调退避；
5. **多尺度目标冲突**（帧级安全 vs 部署级疲劳）→ 字典序约束 + 证书公开权重；
6. **门控近似误差**累积 → 由引理 21 显式预算 `δ_gate`，超预算即全开。

| `℘(o)` | 状态 `o` 下的活跃痛点集 |
| `R=E[L]`, `CVaR_α(L)` | 期望痛点风险 / 尾部条件风险 |
| `q_k(ξ,o)=P(p_k\|ξ,o)`, `a_{m,k}` | 痛点后验 / 模态级归因 |
| `H(M)=I(M;L)+H(M\|L)` | 模态熵的痛点精确分解 |
| `U_pain=I(M;L\|o)` | 痛点相关不确定性（→ 交互/收紧） |
| `U_benign=H(M\|L,o)` | 良性歧义（→ BAC 后忽略） |
| `BAC(o)` | 良性歧义证书（UCB(I(M;L)) ≤ ε） |
| `VoPI(g)=ρ*(o)−E[ρ*(o,y)]−c(g)` | 痛点相关信息价值（→ 交互选择） |
| `Δ_m=I(e_m;L\|e_{−m},o)` | 模态边际痛点信息（→ 门控） |
| `γ_m`, `Σγ_m≤B` | 门控权重 / 硬预算 |
| `κ`, `τ_conf` | 模态冲突度 / 冲突阈值 |
| `TCG=(ECE_k, CVaR coverage, selective risk)` | 尾部校准门 |
| `Regret_k` | 痛点反事实遗憾（CPA） |
| `J_TRIAGE=(J_FLUID, atlas_ver, U_pain, U_benign, BAC, VoPI_ratio, gate_hash, conflict_stats, TCG_report, CPA_regret, triage_ver)` | 证书 |

## 2. 形式化定义（要点版）

**定义 310（总览与三不变式）** 三不变式：均匀痛点边界逐指令等价 FLUID；良性歧义须经 BAC 认证，否则按痛点相关处理；尾部安全 + TRIAGE→FLUID→R68 单调退避。

**定义 311–312（痛点图谱与 CVaR）** `p_k=(A_k,L_k,H_k,c_k)`；`℘` 带频率/严重度/溯源与版本；风险用 `(R,CVaR_α)` 二元组，灾难性痛点设 `P(p_k)≤ε_k` 硬约束；五步流程：识别→排序→归因→干预→验证。

**定义 313（PAX）** 输出 `q_k(ξ,o)`、条件损失分布与模态归因 `a_{m,k}`；归因用于门控监督与冲突诊断。

**定义 314–315（PRU 与 BAC）** `H(M|o)=I(M;L|o)+H(M|L,o)`；仅 `U_pain` 触发交互，`U_benign` 经 `UCB(I(M;L))≤ε_benign` 认证后忽略；认证失败则保守归入 `U_pain`。

**定义 316（VoPI）** `VoPI(g)=ρ*(o)−E_y[ρ*(o,y)]−c(g)`；`VoPI≤0` 不交互；均匀痛点时退化为 R69 的 `VoI`；信息动作含「打开模态/换视角/换问法」。

**定义 317–318（GMF 与融合经济）** 门 `γ_m=σ(⟨u_m,φ(℘(o))⟩)`，硬预算 `Σγ≤B`、硬门 `Δ_m≤ε_gate⇒0`；`L_GMF=L_pain+λI(z;e|L)+μ·compute`；引理 21 给出丢模态的风险上界 `ℓ_max√(ε/2)`。

**定义 319（CAF）** `κ≤τ_conf` 用 product-of-experts；`κ>τ_conf` 用稳健混合 + 尾部可靠性权重，并登记 `p_conf`；不静默平均；滞回 `h` 步。

**定义 320（TCG）** 痛点条件 ECE + CVaR 覆盖率 + 选择性风险三项同时过关；否则禁用痛点分诊，退 FLUID 的 MCG，再退 R68。

**定义 321（PED）** 一致须在痛点标签 `P` 与痛点相关子空间上，且有效独立；单源/单次永不定案；无关维度的一致不算证据。

**定义 322–323（MSA 与分诊）** 帧级/回合级/部署级三层独立校准与门控；字典序：灾难性约束 → 软痛点 `CVaR_α` → 交互/算力成本；不可行则弃权并输出分诊证书。

**定义 324（CPA）** 双重稳健/IPS 估计 TRIAGE/FLUID/R68 的反事实痛点遗憾；回灌图谱修订、TCG 重校准、候选痛点发现（人工复核后入谱）。

**定义 325–327（威胁、证书、主序）** `ℰ_TRIAGE=ℰ_FLUID×ℰ_pain×ℰ_fusion`（痛点投毒/DoS、模态捕获、伪相关融合、共同原因污染）；`J_TRIAGE` 并入图谱版本、`U_pain/U_benign`、BAC、门控/冲突、TCG、CPA；主序固定为识别→融合→采样→分解→校准→分诊→认证→审计。

## 3. 关键算法伪代码

```python
# IP-264 PPA：痛点图谱（识别/排序/溯源/版本化）
class PainAtlas:
    def active(self, o): return [k for k in self.points if self.q[k](o) > TAU_ACTIVE]
    def rank(self, k):   return (self.points[k].catastrophic, self.pi[k]*self.nu[k])
    def revise(self, report): ...          # 仅接受人工复核的候选痛点

# IP-265 PAX：痛点后验 + CVaR + 模态归因
def pain_risk(modes, o, atlas):
    q = [atlas.posterior(xi, o) for xi in modes.prototypes]
    L = [atlas.loss(qk) for qk in q]
    return expected(L), cvar(L, 0.95), q

# IP-266 PRU：R69 模态熵的痛点精确分解
def decompose_pain(modes, w, loss_post):
    H_M      = entropy(w)
    U_pain   = mutual_info(mode_identity, loss_post)   # I(M;L|o)
    U_benign = max(0.0, H_M - U_pain)                  # H(M|L,o)
    return U_pain, U_benign

def benign_certificate(U_benign, calib):
    return calib.ucb(U_benign, delta=1e-3) <= EPS_BENIGN

# IP-267 VoPI：只买“能减痛”的信息
def choose_info(modes, o, atlas, budget):
    rho0, best = triage_risk(modes, o, atlas), None
    for g in info_candidates(modes, atlas):            # 看/问/触/开模态/换视角
        if not budget.allow(g) or not c_ras_wm.certify_info(g, o): continue
        rho1  = E_y[triage_risk(bayes_update(modes, y, g), o, atlas)]
        score = pain_gain(rho0, rho1) - cost(g)        # 字典序比较
        if best is None or score > best.score: best = (g, score)
    return best if best and best.score > 0 else None   # 无痛可减 → 不交互

# IP-268/269 GMF + CAF：痛点门控融合，冲突转稳健聚合
def gated_fusion(obs, active, gates):
    ev = {m: enc[m](obs[m]) for m in obs if gates.delta[m] > EPS_GATE}
    kappa = conflict(ev, active)
    z = product_of_experts(ev) if kappa <= TAU_CONF else robust_mixture(ev, tail_reliability(ev))
    return z, kappa

# IP-270 TCG：全局 ECE 不够，必须在痛点上校准
def tail_gate(pred, emp, active):
    return (ece_conditional(pred, emp, active) <= TAU_ECE
            and cvar_coverage(pred, emp) <= TAU_CVAR
            and selective_risk(pred, emp) <= TAU_SEL)

# IP-275 主闭环：TRIAGE 插在 R69 的不确定性处置处，反射环不变
def TRIAGE_round(M, obs):
    z, o = M.mtm.forward(...); c, U_cal, thr = M.cof.step(...)
    active = M.ppa.active(o)
    zf, kappa = M.gmf.fuse(obs, active)
    if kappa > TAU_CONF: active = active + [M.ppa.conflict_point(obs)]
    K = 1 if M.fmp.mode_head(zf) < TAU_MODE else 4
    samples = M.fmp.sample(zf, K)
    U_ale, U_epi, modes = M.aud.decompose(samples)
    U_pain, U_benign = M.pru.decompose_pain(modes, modes.w, M.pax.loss_posterior)
    bac = M.pru.benign_certificate(U_benign, M.calib)
    if not M.tcg.pass_(M.pax, o, active):
        return M.fluid_round(o)                        # 尾部不可信 → 退 FLUID → R68
    g = (M.vopi.choose_info(modes, o, M.ppa, M.budget)
         if (U_pain > TAU_PAIN and bac) else None)
    if g is not None:
        U_pain = M.cia.update_pain(modes, M.cia.execute(g))
    U_floor = U_ale + (U_pain if g is None else 0.0)   # U_benign 不进 λ
    lam = max(M.efs.risk_scale(...), lam_floor(U_floor))
    k = M.c_ras_wm.certified_prefix(M.ach.propose(...), ..., wm_preds)
    mode = select_mode(modes, U_pain, lam)
    M.cpa.log(o, active, g, U_pain, U_benign, counterfactuals=True)
    return k, lam, mode, (U_pain, U_benign)
```

## 4. 推导

**引理 19（痛点无关 ⇒ 零信息价值）** `H(M|o)=I(M;L|o)+H(M|L,o)`。若 `U_pain=0`，则 `L⫫M|o`，任何信息动作不改变 `L` 后验，`VoPI=−c≤0`；一般期望痛点下降 `≤ℓ_max√(U_pain/2)`。系：R69 用 `H(M)` 触发交互，超出 `U_pain` 的部分是无效提问。

**引理 20（全局校准不能证明尾部）** 痛点区概率 `π`、`ECE_A=1`、良性区 `ECE_B=0`，则全局 `ECE=π`，可取 `π<τ_ece` 而尾部误差仍为 1；下界 `ECE_A≥(ECE_global−(1−π)ECE_B)/π` 在小 `π` 时几乎无信息。故 R69 的全局 ECE 门不能守住其尾部风险。

**引理 21（门控融合风险上界）** `Δ_m≤ε ⇒` 去掉 `m` 的期望痛点风险增加 `≤ℓ_max√(ε/2)`；存在 `ε_gate(δ)` 使门控相对全融合的风险增加 `≤δ`。低相关模态还增加有限样本风险估计方差，故门控在统计上不劣于全融合。

**定理 18（TRIAGE 严格包含 FLUID）** (i) 均匀痛点 + 全相关 + TCG 通过时，`U_pain=H(M)`、`U_benign=0`、全门开、`VoPI=VoI`，逐指令等价 FLUID；(ii) 一般情形，BAC 与 TCG 通过时风险 `≤FLUID+δ_gate`（`ε_gate→0` 时严格 `≤`），交互与算力不高于 FLUID；(iii) 任一认证失败则 TRIAGE→FLUID→R68 单调退化，安全侧不弱于 R68。

**定理 19（尾部安全与单调退避）** TCG 通过且灾难性约束以有效上界执行时，`CVaR_α` 不超过证书声明值；BAC/TCG/冲突/超时任一失败则沿 TRIAGE→FLUID→R68 单调退避；动作均过 C-RAS-WM；门控与冲突滞后 ⇒ 控制连续、无突变。

**推论 19.1（R69 最大风险的局部化）** 幻觉模态若痛点无关，则 `U_pain=0`、经 BAC 后被忽略（无害）；若痛点相关，则抬升 `U_pain` 并触发 TCG：尾部失准则不提问/不自主执行，校准通过则被纳入受尾部约束的概率。R69 的「问错比不问更危险」被分解为「痛相关 + 尾部失校准」两个可测条件。

## 7. 本轮最大风险

**一句话**：TRIAGE 的全部收益都押在「痛点图谱完整且未污染」上——**若真实痛点没被写进图谱，或被人为删掉，系统会把指向它的歧义认证为「良性」并高效忽略；它不是看错了，而是根本没看——「被证实的良性」会让它连疼都感觉不到**。这是对 R69「问错比不问更危险」的反面补充：**分诊错了，不问比问更危险。**

**次级风险与缓解**：尾部数据稀疏 → 保守先验 + 分层校准，不过即退 R69；模态捕获 → 门控熵/反捕获正则 + 归因审计；图谱投毒/DoS → 溯源 + 人工复核 + E311；冲突抖动 → 滞回 + 单调退避；多尺度冲突 → 字典序 + 公开权重；门控近似误差 → 引理 21 显式预算，超预算即全开。
