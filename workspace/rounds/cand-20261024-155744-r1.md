# 第 8 轮 · STANCE：先放身体，再放物体——pivot 是官方演示里被冻结的自由度

> 检索/复核日期：2026-10-24（UTC）。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「步态规划」「产学研合作」「UniBot」。承接第 7 轮 PILOT，本轮不再加一个 VLA 头，而是把注意力移到动作空间里一个被所有人忽略的通道：**7 维 `action.pivot`**。主判断是：**官方 33k 演示把 pivot 几乎冻结成常数，模型因此学成“固定底座的桌面专家”；而评测的位置、背景、人干扰轴恰恰需要先改站姿。用测试时的站姿规划器（SP）把身体放到“可及 + 可见 + 稳定”的甜点，再交给任意 VLA 做手臂操作，是比再堆一个 VLA 头更低成本、更可证伪的杠杆。** 先说明：榜单仍是占位，“榜首 <30%”来自占位 JSON，不是真实排名；本轮分析的是公开模型家族，不是真实头部队伍。

## 0. 本轮先核实：七个事实

### 0.1 榜单/运行记录仍是占位，“榜首 <30%”不是真实数据

截至 2026-10-24（UTC）：

- `leaderboard.html` 仍是「即将发布 / Coming Soon」；`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，8 个模型 × 32 任务、256 条 `task_metrics` 仍是脚本生成（[S10]）。本轮直连 JSON 返回 7,351 字节反爬 HTML，本地缓存 `/tmp/lb.json` 仍是占位结构。
- `runs.html` 仍是占位；详情页写明测试视频占位（[S9]）。
- 用户看到的“榜首不到 30%”对应占位 JSON 的 **MolmoAct2 29.7% / 步骤分 39.0**。同组占位模型：WALL-OSS-0.5 28.5/38.9、DreamZero 27.9/37.9、Spirit-v1.5 25.9/34.4、DM0 23.5/31.7、PI-0.5 22.8/30.6、GigaBrain-0 22.6/29.5、GR00T N1.5 20.5/28.1。

**结论**：这些数字只能当“难度先验/模型池线索”，不能当真实榜单，也不能反推真实头部方案。本轮把“头部方案”改写成“公开模型家族的方法与瓶颈”，并明确标注占位。

### 0.2 提交接口只给了一个下身通道：`action.pivot [7]`

提交 README v2 的动作目录（[S6]）写得很清楚：

| 键 | 形状 | 控制空间 | 说明 |
|---|---|---|---|
| `action.left_gripper` | `[1]` | shared | 左夹爪目标 |
| `action.right_gripper` | `[1]` | shared | 右夹爪目标 |
| **`action.pivot`** | **`[7]`** | **shared** | **Lower-body / pivot target** |
| `action.left_arm` | `[7]` | `joint` | 左臂关节目标 |
| `action.right_arm` | `[7]` | `joint` | 右臂关节目标 |
| `action.left_ee_pose_gripper_base` | `[6]` | `ee` | 左夹爪 base 系位姿 |
| `action.right_ee_pose_gripper_base` | `[6]` | `ee` | 右夹爪 base 系位姿 |

`control_space` 只能在 `joint` 与 `ee` 之间二选一；但 `pivot` 与两个夹爪是两种控制空间都必须返回的 shared 键。**接口没有单独的 waist/leg 键，7 维 pivot 就是提交侧唯一能控制底座/下身的抽象。**

对照数据集，官方内部日志其实有更丰富的下身字段：`action.lower_body [15]`、`action.left_leg [6]`、`action.right_leg [6]`、`action.base_command [4]`、`action.action_torso [6]`、`action.waist_action_joint [3]`，以及 `action.pivot [7]`（[S31][S32][S33]）。提交侧只保留 pivot，说明这是官方刻意压缩后的“下身接口”，而不是数据里没有。**我们不应该因为它难用就忽略它；它恰好是别人不碰的空白。**

### 0.3 pivot 语义审计：高度可信的推断，但仍不是官方文档

官方 README 只写“Lower-body / pivot target”，没有给逐维定义。我们用数据做了一次交叉审计（HangCup 第一个 shard，130,565 帧）：

| 证据 | 数值 | 推断 |
|---|---|---|
| 样本 `action.pivot` | `[0, 0, -0, 0, 0.15, 0, 0.74]` | 7 维 |
| `action.base_command` | `[0, 0, -0, 0.74]` | 前三维底座速度 + 高度 |
| pivot[6] 与 base_command[3] 的相关系数 | **1.000** | pivot[6] = **height** |
| pivot[4] | 恒 **0.15** | 躯干 pitch 目标 |
| `state_torso` 实测 pitch | 0.125–0.204，均值 0.1685 | 0.15 是目标，实测有跟踪误差 |
| pivot[3] / pivot[5] | 恒 **0** | roll / yaw 目标 |
| `state_torso` 实测 roll / yaw | 约 -0.010 / -0.043 | 0 是目标，实测有小偏差 |
| pivot[0:3] | 最大 0.003，几乎全 0 | 底座 vx/vy/vyaw（速度或增量） |

因此推断顺序为：

```text
action.pivot = [vx, vy, vyaw, roll, pitch, yaw, height]
```

其中前三维是底座平移/偏航命令（速度或增量，官方未说明），后四维是躯干姿态 + 底座高度。**这是推断，必须标“未核实”。** 第 8 轮 W1 要用一个小 delta 的 liveness probe 验证：发一个安全的小 pivot，观察头部画面/腿部本体是否变化；如果完全不动，整个站姿假设立刻停止。

### 0.4 官方演示把 pivot 冻结成准常数

我下载了 3 个任务的首个 data shard，统计 `action.pivot` 的实际使用率（[S31][S32][S33]）：

| 任务 | episodes / frames | 任一 `|vx,vy,vyaw|>0.005` 的帧 | height 范围 | pitch 取值 | 解读 |
|---|---:|---:|---|---|---|
| HangCup | 719 / 130,565 | **0（0%）** | 0.721–0.740 | 仅 0.15 | 底座完全冻结 |
| Organize Bookshelf | 304 / 127,020 | **25（0.020%）** | 0.699–0.740 | 0 / 0.15 | 极少数帧有微小 vy/高度变化 |
| Stack Bowls | 412 / 127,651 | **23（0.018%）** | 0.727–0.740 | 仅 0.15 | 极少数帧有微小 vx/高度变化 |

更细的统计：

- HangCup：`vx` 最大 0.003，`vy` 最大约 2e-5，`vyaw` 恒 0；height 只有 12 个不同值，跨度 1.9 cm；roll/yaw 恒 0，pitch 恒 0.15。
- Bookshelf：只有 1 个 episode 出现 `vy=-0.055` 的短段；height 只有 4 个值，跨度 4.1 cm；pitch 只有 0 和 0.15 两个值。
- StackBowls：`vx` 最大约 4e-6 量级，`vy` 最大约 3e-5；height 4 个值，跨度 1.3 cm；pitch 恒 0.15。
- 作为对照，`state_torso` 的 waist 实际有小幅运动：pitch 0.125–0.204，yaw -0.054–0.050，roll -0.042–0.024；也就是说**腰部在动，底座不动**。

**结论**：官方演示是“固定底座 + 轻微 waist”的桌面操作。33k 演示不会教模型使用 pivot；模型学到的最优策略就是 `pivot ≈ 常数`。这不是模型能力问题，是数据分布问题。

### 0.5 站姿压力是任务相关的：Bookshelf/StackBowls 紧，HangCup 松

用同一批 shard 统计末端执行器相对 base 的“相对可达压力”（注意：这是相对 base 原点的径向距离，不是肩部绝对可达半径；只用于任务间对比）：

| 任务 | 左/右 EE 径向 >0.6 m 的帧 | 至少一侧 episode 最大 >0.6 m | 至少一个关节余量 <5% 的 episode（左/右） | 至少一侧手臂偏航 >30° 的 episode | 解读 |
|---|---:|---:|---:|---:|---|
| Organize Bookshelf | **10.8% / 0.1%** | **79.3% / 2.3%** | **42.8% / 76.3%** | 100% / 100% | 最需要站姿 |
| Stack Bowls | 0% / 0% | 0% / 0% | **54.1% / 18.4%** | 100% / 100% | 手腕/肘部压力大，站姿可缓解 |
| HangCup | 0% / 0% | 0% / 0% | 1.1% / 8.9% | 95% / 100% | 舒适，站姿收益小 |

补充：

- **侧向工作角**：所有 3 个任务的每个 episode，至少有一侧手臂相对矢状面偏航 >30°；Bookshelf 右臂 p50=37.1°、p99=61.8°，84.9% 的 episode 最大值 >45°。这说明桌面任务并不是“正前方小范围”，而是有明显的侧向伸展。
- **关节余量**：Bookshelf 左/右臂分别有 42.8%/76.3% 的 episode 至少一个关节进入限位 5% 以内；StackBowls 为 54.1%/18.4%；HangCup 只有 1.1%/8.9%。
- **手腕 yaw 贴限位**很常见（Bookshelf 左 67.4% episode，StackBowls 左 83.3%），但这可能是抓取姿态导致，不一定代表可达性；只作为诊断信号，不作为“必须站姿”的证明。
- **双臂权衡**：如果同时要求两侧都居中，单次 yaw 的收益会被另一侧抵消；所以 planner 必须对双臂加权，而不是只优化“当前手”。单臂任务（或一次只动一侧）收益最大。

**结论**：不要全任务铺开。先打 **T08 Organize Bookshelf**（reach-stressed）和 **T27 Stack Bowls**（wrist/elbow-stressed），用 **T01 HangCup** 作对照（预期收益小，用来防止“ planner 到处乱动”）。这比“32 任务都上站姿”更可证伪。

### 0.6 公开模型家族是“手臂 + 数据”的竞赛，身体是空白

占位榜的 8 个模型正好覆盖了当前公开模型家族的几条主线（[S10][S41][S42][S43][S44]）：

| 模型家族 | 动作空间/方法 | 强项 | 瓶颈 | 站姿机会 |
|---|---|---|---|---|
| MolmoAct2 | 26-D 双臂动作 + 动作推理/flow matching | 空间推理、开放数据、低延迟 | 训练于固定底座双臂；没有 G1 下身 | 站姿 wrapper 补身体 |
| WALL-OSS-0.5 | 4B、20+ embodiments、1M+ trajectories、26-D | 跨本体、数据规模 | 单帧、固定动作维、无全身 | wrapper 与本体无关 |
| DreamZero | 14B video world-action model、7 Hz | 视频预测、泛化 | 重、延迟、无接触力；底座固定 | 站姿改变视角，可能改善预测；但成本高 |
| GigaBrain-0 | world-model 生成数据、RGBD、CoT | 数据引擎、泛化 | 生成数据不含站姿动力学 | wrapper 互补 |
| GR00T N1.5 | 人形基础模型 | 最接近 G1 | 上下身解耦；无显式站姿规划 | 站姿层正好补上 |
| PI-0.5 / Spirit-v1.5 / DM0 | 通才 VLA / WAM | 语义、泛化 | 手臂中心、固定底座 | 同上 |

**占位榜不是真实排名**，但这些公开模型家族的共同范式很清楚：大家都在优化“手做什么”和“数据够不够”，很少有人把“身体站哪”当成一等公民。**这就是本轮要占的空白。**

### 0.7 文献把“站姿”从直觉变成可测杠杆

本轮检索到的直接证据：

- **Visible-Reachable Workspace**（arXiv 2609.08905，[S39]）：固定头部 G1 的 visible-reachable 区域只有约 16%；相机可动后 38%→97%；双相机可动减少完成时间 17%、能量 19%。→ 视角/站姿直接决定“看得到且够得到”的工作区。
- **Base placement**（arXiv 2304.08246，[S40]）：远物抓取时，正确 base 放置的成功率 81.7% vs 40%。→ 底座位置不是小事。
- **STRIDER**（arXiv 2609.23483，[S35]）：stepping/foothold tracking 的多步态分层 loco-manipulation； stance/foot placement 误差会传到末端。→ 站姿精度会影响操作。
- **WholeBodyVLA**（ICLR 2026，arXiv 2512.11047，[S36]）：manipulation-aware locomotion，侧步、下蹲、转身，比基线 +21.3%；VLA 可以同时输出 locomotion command 和手臂动作。→ 全身接口有效，但需要大量数据/训练。
- **HAF-VLA**（CoRL 2026，arXiv 2610.26584，[S37]）：先 locomotion/head，再 waist，再 arms 的分层动作流；比基线 +15.4pp。→ **先身体、后手臂**的顺序本身有收益。
- **MotionWAM**（arXiv 2606.09215，[S38]）：统一 whole-body motion token，G1 上 +32%（43.9→76.1）。→ 统一全身动作空间比上下身分离更强。

这些工作大多是“训练一个大系统”。我们的不同点是：**挑战数据里 pivot 几乎不动，训练全身 VLA 既缺数据又贵；先用一个测试时的确定性 planner 把现有 VLA 的身体摆对，是更便宜的第一步。** 如果 planner 有效，再考虑 stance token 微调；如果无效，立刻停。

## 1. 三个灵感词钉到 UniBot 上

### 1.1 步态规划 → 站姿规划：不是边走边操作，是“先站对再动手”

UniBot 是桌面任务，不需要连续行走；它需要的是**准静态、离散的站姿**：

```text
stance = [base_x, base_y, base_yaw, height, torso_pitch, torso_roll]
```

接口只给 7 维 pivot，没有 foothold/leg 命令；连续步态既不可用也不安全。所以本轮把“步态规划”翻译成 **stance gait / micro-gait**：在 episode reset 和子任务边界选择 1–2 个站姿，慢速执行，然后让手臂操作。它不是步态控制，而是**身体放置（body placement）**。

一句话：**“先放身体，再放物体。”** 第 7 轮把终局放置当闸门；本轮把“身体放置”当前置闸门。

### 1.2 产学研合作 → 站姿压力测试网络（L2L-2）

第 7 轮的 L2L 是“数据农场”。本轮升级为 **L2L-2：站姿压力测试 + 人类站姿先验 + 红队评估网络**，理由：

1. **评估比数据更合规**：外部实验室只跑统一评测协议、回传成功/失败与视频，不并入训练；默认 `external_lab_data: false`，避免规则风险。
2. **真机反馈比自建孪生可信**：挑战没有真实榜单、调试槽稀缺；3–5 个有 G1 的高校实验室可以组成“影子榜”，在桌高 × 距离 × 背景的网格上跑同一套任务。
3. **人类站姿研究便宜且可用**：10 名人类做 5 个桌面任务，动作捕捉躯干/底座站姿，推导 planner 的代价权重；不需要机器人数据，也不涉及第三方黑箱数据。
4. **宇树产业学院是现成节点**：青岛城市学院-宇树科技产业学院（2025-12 揭牌，1 万平米、30+ 台套、含 G1/H2/R1；[S27]）可以作为首站；学生竞赛/课程/联合署名是激励。
5. **产出可开源**：协议、失败地图、planner 代码、benchmark 可以联合署名开源；比赛核心 IP 赛后再说。

这不是“挂名合作”，而是把“站姿多样性”和“真机验证”外包给实验室网络，同时不碰训练数据合规红线。

### 1.3 UniBot → 评分结构决定“站姿是跨轴杠杆”

第 7 轮已核实：32 任务、终局步骤合计 1275/3200=39.8%、放置类约 59.7%、每任务 5 条英文复述、5 个泛化轴、180s、单模型、远程 API。站姿不是只影响“位置轴”，它同时影响：

| 泛化轴 | 站姿的作用 |
|---|---|
| 位置（远/近/侧） | 前移/侧移/转体，把目标放回手臂甜点 |
| 背景/视角 | 改变头部相机视角，减少遮挡/出画 |
| 未见物体 | 更好的视角和可达性，减少“看不见/够不到” |
| 人干扰 | 目标移动后重新选站姿，避开人的工作区 |
| 干扰物 | 底座/躯干避开障碍，给手臂留通道 |

所以站姿是**跨轴资产**，但它不是替代终局放置；它是让 PGL/OPT/SVL 的终局放置更容易。先打 T08/T27/T10，T01 作对照。

## 2. 本轮主判断：不是“不会放”，是“站错了”

### 2.1 一个更锋利的失败模型

| # | 失败模式 | 机制 | 站姿对策 |
|---|---|---|---|
| F1 | 远/侧目标超出舒适可达 | IK 接近限位，肩部/躯干代偿，精度下降 | 前移/侧移/转体，恢复关节余量 |
| F2 | 目标/容器被遮挡或出画 | 固定头部视角差，腕部相机也看不到 | 底座 yaw/height + 躯干 pitch，换视角 |
| F3 | 双臂任务一侧够不到 | 底座偏心，一侧伸展、一侧折叠 | 居中站姿，双臂加权 |
| F4 | 桌面高度不适配 | 肩/腰代偿，末端力臂差 | 高度 + 躯干 pitch |
| F5 | 人干扰/移动目标 | 固定站姿无法避让/重定位 | 子任务边界重规划站姿 |
| F6 | 放置精度差 | 目标在视野边缘/工作区边缘 | 站姿把目标放回“可见-可达”中心 |

这些失败在官方演示里被“固定站姿”掩盖：模型学会“伸手够，够不到就失败”，而不是“先挪一步”。

### 2.2 为什么这比“再堆一个 VLA 头”更该做

- **零/低训练**：planner 是确定性采样 + IK/几何评分，不需要 33k 之外的数据；可以直接套在 MolmoAct2/WALL-OSS/GR00T/GPR-VLA 上。
- **单模型合规**：planner 不是学习模型；唯一学习模型仍是 VLA。若后续加 stance token 微调，也只是同一个 checkpoint，不增加第二个模型。
- **可证伪**：离线统计 + 仿真 + 1 个调试槽就能判断；如果 pivot 被评测忽略/夹紧，W1 立刻停。
- **与第 7 轮叠加**：SSG 给子任务边界，PGL/OPT 给目标位姿，SVL 给落点闭环；SP 只负责“身体放哪”。
- **竞争空白**：公开模型家族都在优化手臂/数据；很少有人把 pivot 当一等公民。

### 2.3 与第 7 轮的关系：保留主干，换一个攻击面

| 处置 | 内容 |
|---|---|
| **保留** | GPR-VLA 主干、SSG 评分步骤图、PGL 放置目标阶梯、OPT 少样本位姿迁移、SVL 落点闭环、NRB 官方备注恢复、L2L、DebugLoop、TLE/ACP/GF、AH-TP/Endurance/Compliance guards |
| **升级** | L2L → **L2L-2 站姿压力测试网络**；DebugLoop → **stance A/B**；PGL/OPT 的目标位姿进入 SP 评分；SSG 提供 replan 边界 |
| **新增** | **I14 SPM** 离线站姿先验挖掘、**I15 SP** 测试时站姿规划、**I16 SG** pivot 执行/安全 governor；可选 **I17 SAP** stance token 微调 |

## 4. 风险与合规（先立后破）

- **P0：pivot 语义/活性未知**。评测端可能忽略/夹紧 pivot；W1 先做小 delta liveness probe。若完全不动 → 全停，回到第 7 轮。
- **P1：底座移动的安全**。桌边碰撞、倾斜、急停；先退臂、再慢移、限速/限幅、电流/倾角监控；只做准静态，不做动态步态。
- **P2：视角 OOD**。VLA 可能在新的 base 视角下性能下降；初始只允许 ≤0.10 m、≤20°、≤4 cm 的小站姿变化，逐步放大。
- **P3：时间预算**。planner 50–100 ms，执行 1–3 s，每 episode 最多 2 次；180s 内可承受。
- **P4：单模型合规**。SP/SG 是确定性代码；不得引入第二个学习模型；模型卡写清。
- **P5：外部数据**。L2L-2 默认只做评估，不并入训练；邮件确认后再开。
- **P6：占位榜**。不根据占位分数调参；只把它当模型池/难度线索。
- **P7：真机资源**。调试槽稀缺；每版本最多 1 槽，配对 A/B，记录失败类型。

## 5. 一句话押注

**UniBot 的下一分不在“手更聪明”，而在“身体站对”：官方 33k 演示把 7 维 pivot 冻结成常数，谁先把站姿规划成“可及 + 可见 + 稳定”的甜点，谁就能在不换 VLA 的情况下，把位置/背景/干扰轴的失败率往下拉——先放身体，再放物体。**

## 2. 评分算术：为什么站姿是杠杆

### 2.1 已知结构

- 32 任务，满分 100；成功 = 所有步骤完成；终局步骤合计 **1275/3200=39.8%**；放置/插入/堆叠类约 **59.7%**（第 7 轮）。
- 5 个泛化轴：位置、干扰物、背景、未见物体、人为干扰；通才单模型；180s；远程真机 API。
- 每任务 5 条英文复述（32×5=160）；SSG 可在内部把指令映射到步骤图。

### 2.2 站姿的跨轴作用

| 轴 | 站姿作用 | 预期 |
|---|---|---|
| 位置（远/近/侧） | 前移/侧移/转体，把目标放回关节余量大的区域 | 最大 |
| 背景/视角 | 改变头部相机视角，减少遮挡/出画 | 中 |
| 未见物体 | 更好视角/可达性，减少“看不见/够不到” | 中 |
| 人干扰 | 目标移动后重新选站姿，避开人的工作区 | 中 |
| 干扰物 | 底座/躯干避开障碍，给手臂留通道 | 小–中 |

站姿不是替代终局放置；它让 PGL/OPT/SVL 的目标更容易被看到、够到、放准。

### 2.3 增益模型

```text
Δ总分 ≈ p_stress × Δsucc_stance × q_terminal
```

- `p_stress` 来自 SPM：至少一个关节余量 <10%、或 EE 侧向角 >45°、或目标/容器出画的 episode 比例。
- `Δsucc_stance` 来自仿真/真机 A/B；先估 0.10，保守。
- `q_terminal` 是到达终局步骤的通过率；第 7 轮估 0.5–0.7。

示例：

| p_stress | Δsucc | q | Δ总分 |
|---:|---:|---:|---:|
| 0.2 | 0.08 | 0.6 | +0.96pp |
| 0.4 | 0.10 | 0.6 | +2.4pp |
| 0.6 | 0.15 | 0.6 | +5.4pp |

如果 p_stress 只有 0.1，站姿不值得做；如果 p_stress 高但 A/B 无增益，也不值得做。

### 2.4 时间预算

- planner：50–100 ms/次；每 episode 1–2 次。
- 执行：1–3 s/次（慢速平移/转体/升降 + settle）。
- 总成本：<5 s；180s 预算内可承受。
- 长程任务（T16/T17/T31）限制 1 次；接触中不移动。

### 2.5 优先任务

## 3. STANCE-GPR 架构

### 3.1 总览

```text
语言 → SSG 评分步骤图 → 当前子任务 s
                              │
                              ▼
              SPM 离线：任务站姿画像 / 压力图
                              │
                              ▼
              SP 站姿规划（reset / 子任务边界）
      候选 5-D stance → IK / 可见 / 碰撞 / 平衡 / 运动代价 → p*
                              │
                              ▼
              SG pivot governor：退臂 → 慢移 → settle → 交接
                              │
                              ▼
      任意 VLA（GPR-VLA / MolmoAct2 / GR00T…）→ 手臂/夹爪
                              │
                              ▼
              PGL / OPT / SVL 终局放置（第 7 轮）
```

### 3.2 设计原则

1. **准静态**：只在 reset/子任务边界移动；接触中不动；不做连续步态。
2. **小步**：初始限制 ≤0.10 m、≤20°、≤4 cm；验证后再放大。
3. **确定性**：SP/SG 不训练；单模型合规；可审计。
4. **模型无关**：VLA 只负责手臂/夹爪；换模型不影响 SP/SG。
5. **可回退**：任何异常 → 当前站姿；不移动也是安全策略。
6. **先退臂**：移动前把双臂收回到安全位，避免扫桌。

### 3.3 控制流伪代码

```python
def act(obs, task_step, vla):
    if should_replan(obs, task_step):
        targets = get_targets(task_step, obs)          # PGL/OPT
        stance = SP.plan(obs, task_step, targets)      # 5-D
        if stance is not None and SG.safe(stance):
            arms_home()
            SG.execute(stance)                         # pivot 慢移
            SG.settle_and_verify()
    arm_action = vla.predict(obs)                      # base 系手臂/夹爪
    pivot = SG.hold_or_zero()
    return merge(arm_action, pivot)
```

## 5. SP：测试时站姿规划

### 5.1 决策变量

```text
stance = [dx, dy, dyaw, height, pitch]
roll = 0（保持水平）
```

- `dx, dy`：相对当前 base 的平移，初始 ±0.10 m。
- `dyaw`：相对当前 base 的偏航，初始 ±20°。
- `height`：绝对高度，0.68–0.80 m，初始 ±0.04 m。
- `pitch`：躯干 pitch 目标，0.05–0.25 rad。

### 5.2 候选空间

```text
dx ∈ {0, ±0.04, ±0.08, ±0.10}
dy ∈ {0, ±0.04, ±0.08, ±0.12}
dyaw ∈ {0, ±10°, ±20°}
height ∈ {0.70, 0.74, 0.78}
pitch ∈ {0.10, 0.15, 0.20}
```

约 7×7×5×3×3=2205 个；用 SPM 先验剪枝到 ~200 个（任务相关的 yaw 方向、height 范围）。

### 5.3 硬约束（先过滤）

- 桌面净空：base/腿/手臂不碰桌。
- 关节限位：IK 解在限位内，余量 ≥5%。
- 平衡：CoM 投影在支撑多边形内，静态稳定裕度 ≥2 cm。
- 高度/俯仰/速度：在 §6.3 限幅内。
- 接触：手臂未夹持/未接触时才允许移动。
- 时间：单次移动 ≤3 s。

### 5.4 代价函数

```text
C(s) = w_r * C_reach(s)
     + w_v * C_vis(s)
     + w_c * C_coll(s)
     + w_b * C_bal(s)
     + w_m * C_motion(s)
     + w_p * C_prior(s)
```

| 项 | 计算 | 初始权重 |
|---|---|---|
| `C_reach` | 对左右手 grasp/place 目标做 IK；取关节余量、可操作度、工作区边界距离的最大惩罚 | 1.0 |
| `C_vis` | 目标/容器投影到头部+腕部相机；惩罚出画、遮挡、分辨率低 | 0.8 |
| `C_coll` | base/腿/臂 vs 桌/物体；胶囊/点云距离 | 1.0（硬约束优先） |
| `C_bal` | CoM 投影到支撑多边形中心距离 | 0.5 |
| `C_motion` | 平移/转体/升降距离 + 时间 | 0.3 |
| `C_prior` | SPM 任务先验（偏好方向/高度） | 0.4 |

### 5.5 实现

- **IK**：Pinocchio + G1 URDF；目标来自 PGL/OPT 的 6D 位姿；左右臂各解一次。
- **感知**：头部双目/RGB-D 或单目深度；桌面平面 RANSAC；物体/容器分割（SAM 类，许可逐个核）；目标点云。
- **可见性**：把目标/容器关键点投影到 4 路相机；检查画内、遮挡（raycast/深度）、像素面积。
- **碰撞**：桌面板 + 物体包围盒/点云；base/腿/臂胶囊；只在候选站姿下做粗略扫掠。
- **平衡**：URDF 质量 + 当前关节角估 CoM；支撑多边形用双脚接触点。
- **缓存**：按任务/步骤/目标区域缓存 top-k 站姿；在线只做局部细化。

### 5.6 求解器

```text
1. 生成/剪枝候选（~200）
2. 硬约束过滤
3. 对每个候选算 C(s)（IK + 投影 + 碰撞 + 平衡）
4. 取 top-10，做 3 轮 CEM 局部细化（连续化 dx/dy/dyaw）
5. 返回最优可行解；否则 None（保持当前站姿）
```

预算：50–100 ms/次（CPU，200 候选，IK 热启动）。如果超时，回退到 SPM 先验的固定站姿。

### 5.7 触发条件

- episode reset（第一次站姿）。
- SSG 步骤切换（如“抓取”→“放置”）。
- 目标丢失/出画（连续 N 帧）。
- 抓取/放置失败（SVL 判定）。
- 人干扰导致目标移动。
- 最多 2 次/episode；接触中不触发。

### 5.8 伪代码

```python
def plan(obs, task_step, targets):
    cands = prune_candidates(SPM.prior(task_step), obs.base_pose)
    feasible = []
    for s in cands:
        if not hard_constraints(s, obs): continue
        ik = solve_ik(targets, s)
        if ik is None: continue
        c = (w_r*reach_cost(ik, s) + w_v*vis_cost(obs, targets, s)
             + w_c*coll_cost(obs, s) + w_b*balance_cost(obs, s)
             + w_m*motion_cost(obs, s) + w_p*prior_cost(task_step, s))
        feasible.append((c, s, ik))
    if not feasible: return None
    return refine_cem(sorted(feasible)[:10], obs, targets)
```

## 6. SG：pivot 执行与安全 governor

### 6.1 pivot 语义假设

两种可能：

| 模式 | 行为 | 执行 |
|---|---|---|
| **速度/增量** | `[vx,vy,vyaw,...]` 是速度命令 | 发 Δt 秒，然后发零；闭环看位移 |
| **位姿目标** | `[x,y,yaw,...]` 是目标 | 发目标并保持；闭环看误差 |

W1 的 liveness probe 区分两者；SG 对两种模式都兼容：发小命令 → 观察 → 到目标后发零/保持。

### 6.2 liveness probe（W1，Go/No-Go）

在**不计分单任务调试**模式（[S8]）中：

1. 选 T01 HangCup（安全、桌面开阔）。
2. 发 `pivot=[0.03,0,0,0,0.15,0,0.74]` 持续 0.4 s，然后 `pivot=[0,0,0,0,0.15,0,0.74]`。
3. 记录：头部画面光流、左右腿关节变化、EE base 位姿变化、`lower_body` 变化、是否有 fault。
4. 重复 yaw：`[0,0,0.15,0,0.15,0,0.74]`；重复 height：`[0,0,0,0,0.15,0,0.78]`。
5. 判定：
   - 全部无变化 → pivot 被忽略/夹紧 → **停止**。
   - 有变化 → 估计符号/尺度/延迟；写入 SG 标定表。
6. 安全：小 delta、慢速、手放在急停；异常立即停。

### 6.3 执行顺序

```text
1. 退臂到安全位（肘弯、腕收、夹爪闭合）
2. 检查桌面净空/倾角/电流
3. 发慢速 pivot chunk（速度模式）或目标（位姿模式）
4. 监控：头部光流、腿本体、EE base 位姿、IMU/电流
5. 到目标/超时 → 发零/保持 → settle 0.2–0.5 s
6. 验证：base 位移/高度/俯仰在容差内
7. 交接给 VLA；记录 stance 日志
```

### 6.4 限幅（初始）

| 量 | 限制 |
|---|---|
| `vx` | ≤0.10 m/s |
| `vy` | ≤0.08 m/s |
| `vyaw` | ≤10°/s |
| 单次平移 | ≤0.10 m |
| 单次偏航 | ≤20° |
| height | 0.68–0.80 m；单次 ≤4 cm |
| pitch | 0.05–0.25 rad；单次 ≤0.05 rad |
| roll | ±0.05 rad |
| 倾角停止 | >3° 或角速度突变 |
| 电流停止 | 超过标定阈值 |
| 接触 | 夹持/接触中禁止移动 |

### 6.5 安全监控

- **头部光流**：判断 base 是否真的动了；如果命令发了但画面不动 → pivot 被忽略。
- **腿本体**：`lower_body`/`left_leg`/`right_leg` 变化；异常抖动 → 停。
- **EE base 位姿**：如果 base 动了但 EE 世界位姿没动，说明手臂补偿；记录。
- **IMU/电流**：倾斜、堵转、桌边碰撞。
- **超时**：命令超过 3 s 未到位 → 停，回退。

### 6.6 伪代码

```python
def execute(stance):
    if not safe(stance): return False
    arms_home()
    for cmd in trajectory(stance, max_speed=LIMITS):
        if not monitors_ok(): stop(); return False
        send_pivot(cmd)
        sleep(dt)
    send_pivot(hold_or_zero(stance))
    settle(0.3)
    return verify(stance)

def hold_or_zero(stance):
    return stance.pivot if MODE == "pose" else ZERO_PIVOT
```

## 7. 与 VLA / 第 7 轮栈的集成

### 7.1 观测/动作映射

- 观测：4 路 RGB、双臂关节/EE、夹爪、lower_body、语言；无显式 base 世界位姿。
- 动作：VLA 出双臂/夹爪；SG 出 pivot；合并成一个 dict。
- base 系：VLA 的 EE 目标是 base 系；站姿改变后，base 系变了。**最安全的做法是站姿 settle 后再让 VLA 重新观测/推理**，不要在同一 chunk 里同时移动 base 和手臂。
- 如果必须连续：把 VLA 的 EE 目标从旧 base 系变换到新 base 系，或让 VLA 以相对目标输出；第一版不做，避免坐标系 bug。

### 7.2 SSG 边界

- SSG 输出当前步骤 `s`；SP 在 `s` 切换时触发。
- 如果 SSG 谓词不确定，SP 不触发（保守）。
- 站姿日志写入 SSG 状态机，便于复盘。

### 7.3 PGL/OPT/SVL

- PGL 给槽位/锚点/6D 位姿；SP 用这些目标算 reach/visibility。
- OPT 给容器系释放位姿；SP 把目标变换到候选 base 系，检查可达。
- SVL 的落点闭环不变；站姿只改变起点，不改变终局判定。

### 7.4 单模型合规

- SP/SG 是确定性代码；不是学习模型。
- VLA 是唯一 checkpoint；SAP（可选）在同一个 checkpoint 上加 stance token，不新增模型。
- 模型卡写清：SPM/SP/SG 的输入输出、限制、失败回退；L2L-2 只用于评估。

### 7.5 可选 SAP：stance token 微调

只有在 SP 证明有效后才做：

- 在 VLA 输入加 7 维 stance token（当前/目标站姿）。
- 在仿真里随机化桌高/距离/站姿，收集 5k–10k 成功轨迹；或用运动学重定向扩展现有演示。
- 只微调 action expert/LoRA，不重训 VLM。
- 目标：让 VLA 学会“在新视角下操作”，减少 SP 的 OOD 风险。

| SP off | 基线 |
| reach-only | 可达是否足够 |
| reach+vis | 视角是否加分 |
| full cost | 平衡/碰撞/运动是否必要 |
| yaw-only / height-only / xy-only | 哪个自由度最值钱 |
| reset-only vs step-boundary | 子任务重规划是否必要 |
| 限制收紧/放宽 | 安全与收益的权衡 |
| GPR-VLA vs 开源基线 | 模型无关性 |

### 9.7 Go/No-Go

| 阶段 | Go | No-Go |
|---|---|---|
| W1 pivot liveness | 有可测位移/姿态变化 | 无变化 → 停 |
| 离线 SPM | `p_stress` ≥0.3 on T08/T27 | <0.1 → 缩范围/停 |
| 仿真 | +5pp 成功率或 +10pp 可达 | 无增益 → 停 |
| 真机 | T08/T27 +5pp，T01 无回归 | 回归/超时/碰撞 → 回退 |
| 全量 | 总分 +2pp，CI>0 | CI 跨 0 → 不上线 |

- 状态：保留；作为 SP 的第一个 VLA 搭档。

### I10 TLE/ACP/GF 数据引擎（保留，修剪）
- 动机：真实锚定反事实仍是最便宜的轴数据。
- 状态：只服务放置/站姿场景；不做全任务。

### I11 AH-TP / Endurance / Compliance guards（保留）
- 作用：谓词时长、180s 守卫、数据来源开关、单模型审计。

### I12 TCLB（降级）
- 从“主评测台”降为“离线相对比较”；站姿主验证靠调试槽 + L2L-2。

### I13 FLEET 工程检查单（降级｜第 6 轮遗产）
- 保留 N 端口/状态隔离/延迟弹性/健康检查；不作为研究贡献。

### I14 SPM 站姿先验挖掘（新增，押注）
- 动机：pivot 冻结是数据事实；需要任务级压力画像来决定“哪里值得站”。
- 差异：把 pivot 方差、EE 径向、侧向角、关节余量合成 `p_stress`；不是通用数据统计。
- 可行性：3 任务已做；32 任务 stats 可批量拉。
- 资源：CPU；1 人周。
- 步骤：全量 stats → 指标 → 任务画像 → planner 先验。
- 风险：径向距离不等于肩部可达 → 用 URDF/仿真校准。

### I15 SP 站姿规划（新增，押注）
- 动机：官方演示冻结 pivot；测试时把身体放到可及+可见+稳定。
- 差异：模型无关、确定性、5-D 准静态；不是连续步态/RL。
- 可行性：IK/投影/碰撞/平衡都是成熟工具；50–100 ms。
- 资源：CPU；1–2 人周；无新数据。
- 步骤：候选 → 硬约束 → 代价 → CEM → 触发/缓存。
- 风险：感知噪声/坐标系；先用仿真/标定，限小步。

### I16 SG pivot 执行/安全 governor（新增，押注）
- 动机：pivot 语义未文档化；真机移动必须安全。
- 差异：liveness probe + 退臂/限幅/监控/回退；兼容速度/位姿两种语义。
- 可行性：接口允许；调试槽可测。
- 资源：1 人周；急停/安全员。
- 步骤：probe → 标定 → 执行 → 监控 → 回退。
- 风险：pivot 被夹紧/忽略 → W1 停；碰撞 → 小步/退臂。

### I17 SAP stance token 微调（新增，可选）
- 动机：SP 改变视角后 VLA 可能 OOD；token 让模型知道站姿。
- 差异：同一 checkpoint 加 7 维 token；只微调 action expert/LoRA。
- 可行性：需仿真/重定向数据；在 SP 有效后做。
- 资源：5k–10k 轨迹；8×H100 数天。
- 风险：数据成本/负迁移；不做也不影响主线。

### 已砍清单（跨轮）
- 连续步态/行走操作；自由仿真 RL；全 32 任务高保真孪生；布料/拉链/透明全物理；WMA-0 进主路径；每任务 LoRA；运行时 MPC；第二阶段大模型。
