## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（语音交互 → 这是一场「单轮语音指令」考试，但多数 VLA 只把指令当背景词）**
直觉：语音助手能工作，不是因为它「听过所有句子」，而是因为它把一句话拆成 **意图 + 槽位**、维护 **对话状态**、并用 **endpointing / barge-in / repair** 决定何时停、何时被打断、何时修复。把机器人放回这个框架：`observation.language` 是整集不变的单轮指令（F23），而 32 个任务里有一批**视觉近邻但语义相反/相近**的任务对——插网线 vs 拔网线、拉拉链 vs 解拉链、装袋 vs 卸袋、叠杯 vs 收杯、开药瓶 vs 倒药。在这些任务对上，语言是唯一可分辨信号。若把指令对调后策略动作几乎不变，它就不是多任务通才，而是「场景条件化的专家」。核心反直觉点：**跨任务泛化的第一道体检不是看成功率，而是看「指令敏感性」——模型是否真的在听。**

三个可直接借用的语音系统部件：
1. **NLU / 槽位解析**：把指令编译成 `(动词, 主题物, 目标, 数量, 约束)` 的类型化程序，而不是一整个 CLIP 文本向量；
2. **对话状态跟踪（DST）**：把任务进度建成里程碑信念状态（I5 进度头的严格版）；
3. **endpointing / barge-in / repair**：成功后的「及时收手」、人工介入时的「让位」、偏离后的「修复式重述」——分别对应 I11、I4、I5 的语音类比。

**灵感 2（评测指标 → 榜单是一个带噪声的复合函数，不是「技能平均分」）**
直觉：官网首页明写按「平均成功率与步骤分综合排序」（F20），每任务又是 100 分制得分点（F17/F21）。这意味着我们优化的不是「某个策略有多强」，而是一个 **32 维向量 (p_i, s_i) 经未知权重聚合后的期望排名**，且每任务只跑少量回合。三条后果：
1. **组合配置比单点突破更值钱**：把 1 个任务从 0→80% 与把 5 个任务从 10→20%，对平均成功率的贡献可能相同，但前者方差更小、步骤分更高；
2. **部分分是免费的地板**：超时仍按得分点计步骤分（F3），所以「稳定拿到第一个里程碑」能在不成功的任务上锁住保底分；
3. **排名是噪声估计**：N 小，p_i 的估计方差为 p(1−p)/N；一个任务的偶然翻车就能改写名次。因此**低方差策略 > 峰值策略**，「清除零分任务」先于「抬高均值」。

核心反直觉点：**在榜首 <30% 的赛况下，最优策略不是提高平均技能，而是先把「零分任务」清零，再把「临界任务」推过线；步骤分只是第二位。**

**统一：从「数据引擎」升级为「数据 × 语言 × 指标」三角**
第 2 轮证明数据引擎抬高 p_i（供给端）。本轮补两个乘数：**语言**决定同一套视觉表征能否被正确路由到不同任务（输入侧可分辨性）；**指标**决定把有限的 p_i/s_i 增量投到哪、何时收手、如何降低排名方差（目标侧配置）。一句话：**数据决定你能做多好，语言决定你做的是不是这道题，指标决定你把力气花在哪道题。** 三者缺一，数据引擎的增益会被「语言盲区」与「配置错误」吃掉。

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2）

> 检索日期：2026-11-26（第 1 轮）、2026-11-27（第 2 轮）、2026-11-27（本轮）；来源见 §5。承接 v1.1：**新增 I10–I12，深化 I1/I2/I5/I9，I3/I4/I6/I7/I8 维持或并入**。清单只增改不重置。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I10 指令编译 + 语言依赖审计 ★★★★★（新）

- **动机**：32 任务中存在大量「视觉近邻、语义相反/相近」对——`plug_in_ethernet` vs `disconnect_ethernet`、`zip_up` vs Unzip（共训语料）、`pack_bag` vs 卸载、`stack_cups` vs `store_cups`、`open_pill_bottle` vs 倒药。初始场景几乎同构，**`observation.language` 是唯一可分辨信号**（F23）。若模型把指令当全局背景词，它会在这些任务上系统性地做错事，且普通成功率诊断看不出原因（P9）。
- **与现有方案差异**：常规 VLA 把 instruction 一次性编码成全局向量，训练信号只有动作回归；本点显式解析槽位，并用「槽位敏感 / 改写不变」二维审计 + 对比式硬负样本，确保语言真正参与路由，而不只是与场景共现。
- **形式定义**：
  - 编译器 `C: l ↦ P = (v, θ, g, n, c)`，分别为动词、主题物、目标、数量、约束。
  - 槽位敏感度 `S = E_{o~D, (i,j)∈MinPair} d(π(o,l_i), π(o,l_j))`：同一观测、最小差异指令下的动作差异（`d` 用 chunk 的归一化 L2 或 DTW）。
  - 改写不变性 `I = E_{l, l'=paraphrase(l)} d(π(o,l), π(o,l'))`：同一意图、不同措辞下的动作差异。
  - 语言依赖度 `L = S / (I + ε)`；目标 `S↑, I↓`。审计判据：`S` 的配对 bootstrap 置信区间含 0，或 `L < τ_L`，即判定「指令盲」。
- **技术可行性**：高。LLM 离线解析 32 条指令；VLM 文本编码器现成；对比损失只在训练期，推理零额外开销（与 I6 预算兼容）。
- **所需资源**：1 人周工程 + 1 GPU 日（嵌入/审计）；LoRA 增量训练 1–2 GPU 日（官方单卡配置即可，F11）。
- **落地步骤**：①32 条指令 → 类型化程序；②用首帧 DINOv2 嵌入自动聚类出视觉近邻对（不靠人工猜）；③在基座上跑二维审计，建立「任务混淆图」；④把近邻对的最小差异指令作硬负样本，加入 `InfoNCE(动作 chunk 特征, 程序嵌入)` 辅助损失；⑤复审计；⑥L0 看跨任务轴 Δp 与近邻对 Δsuccess。
- **风险**：若官方评测指令固定且从不改写，`I` 的收益有限——缓解：辅助损失取小权重并单独消融；若指令过短导致槽位不可分——缓解：程序输入拼接检测框与几何描述，退回结构化路由。

### I11 里程碑状态机 + 得分点对齐的 endpointing ★★★★（新，承接 I5）

- **动机**：步骤分 = 官方得分点（F17/F21，每任务满分 100）；超时仍按进度计步骤分（F3）；成功后的多余动作可能破坏终态。语音交互的 **endpointing** 正是「何时收手」：太早打断会失败，太晚则超时/过冲（P5/P10）。
- **与 I5 差异**：I5 造恢复示教 + 进度头；I11 补四件事：(a) 官方得分点 → 有序里程碑谓词，构成显式 FSM；(b) 单调 HMM 信念滤波，防止进度回跳噪声；(c) 基于**期望边际剩余分**的 stop / continue / recover 决策；(d) 成功后的及时停止（防 overshoot）。
- **形式定义**：
  - 任务 i 的里程碑 `m_{i,1..K_i}`，累计分 `c_{i,k} ∈ [0,100]`，`m_{i,K_i}` 为成功。
  - 检测器 `q_k(t) = P(m_k 为真 | o_t, l)`；信念 `b_t(k)` 用单调 HMM 前向：仅允许 `k→k` 或 `k→k+1`，恢复时允许回退一格。
  - 终止：`b_K > θ_stop` 连续 `τ` 步 → STOP；`b_k < b_{k-1} − δ` → RECOVER。
  - 期望边际值：`ΔV = p_next·(100 − s_now) − r·(s_now − s_fallback)`；`ΔV < 0` 则停止或转恢复。
- **技术可行性**：中-高。得分点文本可离线获取（F21）；弱监督检测器 = 阶段分割 + 物体状态变化 + 人工抽检，不需要逐帧标注。
- **所需资源**：3–5 个试点任务人工标注 1 人周 + 检测器训练 1 GPU 日/任务族；检测器轻量，可异步/边端运行。
- **落地步骤**：①抓 `info.json` 的 `scoring_points`/`score_steps`；②在 `plug_in_ethernet`、`zip_up`、`open_pill_bottle` 三任务定义可验证谓词；③训练检测器 + HMM；④以 guard 形式接入（不替换主策略，只触发 stop/recover）；⑤L0 离线回放测「误停代价 / 漏停代价」；⑥真机 A/B 看步骤分、成功率、超时率。
- **风险**：误检导致早停，把本可成功的任务停死——缓解：`θ_stop` 高 + `τ` 长 + 高价值里程碑未达绝不早停 + 非对称代价训练；得分点文本模糊不可机器判定——缓解：只用可验证子集，其余退回 I5 进度头。

### I12 榜单组合优化器（评测预算配置）★★★★（新，承接 I8）

- **动机**：排名是「平均成功率 + 步骤分」的复合（F20），真机预算稀缺且任务异质（P10/P11）。I8 只负责「测得准」，I12 负责「投得对」：把每个候选干预的离线 Δp_i/Δs_i 折算成期望名次概率，做组合配置。
- **与现有方案差异**：一般队伍按「哪个任务最差就补哪个」的直觉分配精力；本点按**排名的边际效用**分配，并显式处理小样本方差与官方权重未知。
- **形式定义**：
  - 每任务后验 `p_i ~ Beta(α_i, β_i)`（α=成功+1，β=失败+1），`s_i ~ N(μ_i, σ_i²)`。
  - 复合效用族：`U_lex = lex(mean p, mean s)`；`U_w = w·mean p + (1−w)·mean s/100`，`w ∈ [0.5, 0.9]`。
  - 鲁棒选择：`max_subset min_{U∈𝒰} E[rank_score] − λ·Var[rank_score]`（或最小化最大后悔）。
  - **边际效用近似**：`ΔU ≈ (1/32)Σ_i [∂U/∂p_i·Δp_i + ∂U/∂s_i·(Δs_i/100)]`。
  - **成功率-步骤分兑换率**：在 `U_w` 下，单任务 1 个百分点成功率 ≈ `w/(1−w)` 点步骤分（w=0.5→1 点；0.7→2.3 点；0.9→9 点）；lexicographic 下成功率优先，兑换率视为无穷。
  - 三阶段队列：`Z={i: E[score_i]<ε}`（清零）→ `H={i: p_i∈[0.3,0.7]}`（推临界，S 曲线最陡）→ `S={i: p_i 已高}`（收割步骤分）。
- **技术可行性**：高（纯统计 + 现有 L0/L1 数据），无需额外真机即可算。
- **所需资源**：1 人周；算力可忽略；与 I8 注册表共用数据。
- **落地步骤**：①实现 U 族与蒙特卡洛排名；②接 I8 的离线代理；③先用历史/合成先验跑「如果……会怎样」模拟；④每次真机后回填 Beta/Normal 后验；⑤按 Z→H→S 排队，预算只投 top 边际候选。
- **风险**：官方权重未知 → 用 U 族鲁棒优化，不押单一 w；N 太小 → 任务族分层收缩先验；步骤分代理与官方不一致 → PR7 门禁（相关性 <0.6 不许单独准入 L2）。

### 1.2 里程碑 HMM + endpointing（I11）

```python
class MilestoneFSM:
    def __init__(self, K, theta_stop=0.9, tau=5, delta=0.15):
        self.K, self.theta_stop, self.tau, self.delta = K, theta_stop, tau, delta
        self.b = one_hot(0, K)          # 信念：当前至少到达第 k 个里程碑
        self.stable = 0

    def update(self, obs):
        q = self.detector(obs)          # [K] 每个里程碑为真的概率
        self.b = monotone_hmm_forward(self.b, q)   # 只允许 k→k / k→k+1，恢复可回退一格
        k = argmax(self.b)
        if self.b[self.K - 1] > self.theta_stop:
            self.stable += 1
        else:
            self.stable = 0
        if self.stable >= self.tau:
            return "STOP"
        if self.b[k] < self.b_prev[k] - self.delta:
            return "RECOVER"
        return "CONTINUE"

def marginal_value(s_now, p_next, p_fail, s_fallback):
    # 再做一步的期望剩余分 vs 回退保底分；<0 则停/恢复
    return p_next * (100 - s_now) - p_fail * (s_now - s_fallback)
```

### 1.3 榜单组合优化器（I12）

```python
# 单任务 1pp 成功率 ≈ w/(1-w) 点步骤分（U_w 下）；lexicographic 视为成功率优先
def success_step_exchange_rate(w):
    return w / (1 - w)

def sample_leaderboard(posteriors, U, draws=2000):
    out = []
    for _ in range(draws):
        ps = {i: beta.rvs(a, b) for i, (a, b, _, _) in posteriors.items()}
        ss = {i: max(0, min(100, norm.rvs(mu, sig)))
              for i, (_, _, mu, sig) in posteriors.items()}
        out.append(U(mean(ps.values()), mean(ss.values())))
    return out

def allocate(posteriors, interventions, U_family, budget, lam=0.5):
    # interventions[j] = {task: (delta_p, delta_s)}, cost_j
    best = None
    for subset in feasible_subsets(interventions, budget):
        scores = []
        for U in U_family:                       # 权重未知 → 鲁棒
            post = apply_deltas(posteriors, subset)
            scores.append(mean(sample_leaderboard(post, U)))
        util = min(scores) - lam * var(scores)   # 最坏情况 - 方差惩罚
        if best is None or util > best[0]:
            best = (util, subset)
    return best[1]

def priority_queue(posteriors, eps=1e-3):
    Z = [i for i, (a, b, mu, sig) in posteriors.items()
         if a / (a + b) * 100 < eps]                  # 先清零
    H = [i for i, (a, b, _, _) in posteriors.items()
         if 0.3 <= a / (a + b) <= 0.7]                # 再推临界
    S = [i for i in posteriors if i not in Z + H]     # 最后收割步骤分
    return Z, H, S
```

## 2. 官方评分镜像与指标形式化

### 2.1 目标函数与「兑换率」

设任务集 `T={1..32}`，每任务 `n_i` 回合。`p_i` 为成功率，`s_i` 为平均步骤分（0..100）。榜单键为：

```text
mean p = (1/32) Σ p_i
mean s = (1/32) Σ s_i
U_w    = w · mean p + (1−w) · mean s / 100
U_lex  = lexicographic(mean p, mean s)
```

由于首页只写「综合排序」而未给权重（F20），我们不知道 `w`，也不知道是否 lexicographic。**鲁棒做法**：在 `w ∈ [0.5, 0.9]` 上做最坏情况优化，并优先选择在 `U_lex` 与所有 `U_w` 下都不亏的干预。

兑换率（单任务、绝对值）：令 `ΔU_p = w·(0.01/32)`，`ΔU_s = (1−w)·(Δs/100)/32`，令二者相等得：

| w | 1pp 成功率 ≈ 多少点步骤分 |
|---|---|
| 0.5 | 1.0 |
| 0.7 | 2.3 |
| 0.9 | 9.0 |
| lexicographic | ∞（成功率优先） |

**用法**：若某干预能让一个任务成功率 +10pp，而另一干预能让同一任务步骤分 +15 点，则在 w=0.7 下前者更值；在 w=0.9 下前者远更值。这给「补成功率 vs 抠步骤分」提供了可计算的判据，而不是凭感觉。

**注意**：`s_i` 与 `p_i` 相关（成功通常意味着 100 分），所以不要把两者当独立变量重复计算；应直接对「回合级得分」建模，`s_i` 是 `p_i` 与失败时里程碑分的混合。实现上用回合级 bootstrap，而不是两个均值独立相加。
