# 第 22 轮（新灵感循环）· DEPENDABLE-PORTS-SAFETY-ZEST (DPS-ZEST)：从「可靠性」「多端口部署」「安全交互」出发，把通用操作从「单点算法性能」重塑为「可托管、可复现、可安全交互的评测系统」

> 检索日期：2026-11-06。核实结论：用户所指确为**宇树科技 UniBot 世界挑战赛（unibot.unitree.com）**，非其他 UniBot；本轮据此展开。

## 0. 先给直觉：为什么第 21 轮的 CG-ZEST 需要一次「接地校正」？

前 21 轮的 X-ZEST 系列在算法层越挖越深，但建立在一个从未被检验的前提上——**它假设自己是在设计一个"任意接口、任意传感器"的理想认知系统，而不是在参加一场规则精确到端口号的比赛**。第 22 轮先做三处**硬接地（grounding）**，再谈创新：

> **更正 1（传感器接地）**：前 21 轮反复使用 `o_force`（力觉）、`o_tactile`（触觉）、`h_sensor`（力觉健康）作为核心模态。**实际赛题观测目录里没有力觉、没有触觉**——只有 4 路 RGB（两路头部/上位 + 两路腕部）、左右臂关节(7+7)、左右 EE 位姿(6+6)、夹爪开度(1+1)、下肢/腰(15)、以及一条自然语言指令。任何"力觉残差""声纹激励刚度"的推理，都必须改为**由本体感知与视觉可得的代理**重建。{来源：提交仓库 README §2 Observation catalog，2026-11-06}

> **更正 2（部署接地）**：前 21 轮设计了"边缘快策略 → 边缘流合成 → 云端 VLA 升级"的三级级联，隐含"模型之外还有一条云端专家通道"。**实际提交是参赛者本机上的单个 policy 类，经 websocket 被评测器逐帧调用**；没有独立云端路径，网络往返本身就是要被记录的延迟。所谓"慢专家"只能是 policy 内部的第二个前向/第二次采样，且必须算进同一延迟预算。{来源：README §1/§5，2026-11-06}

> **更正 3（评测接地）**：前 21 轮把"成功率"当唯一目标。**实际排名按"平均成功率 + 步骤分"综合排序**；任务有"得分点（满分 100）"（中间步骤可能给分）；且 §6 明确写出评测方会记录**每步响应延迟及其方差、返回动作的统计规律性**，用于结果可信度评估。也就是说：**延迟抖动和异常离群动作会直接进入成绩/信誉评估**——这不是"工程细节"，这是计分项。{来源：challenges.html、README §6，2026-11-06}

**本轮的赌注**：当一个赛道把「真机泛化」与「可托管的稳定服务」放在同一套规则里时（32 任务单模型 + N 端口真机并发评测 + 延迟/动作统计入账），胜负手就不只在模型精度，而在**"可靠性 × 多端口 × 安全交互"这一被严重低估的系统层**。大多数队伍会把 90% 精力投在"把成功率从 20% 推到 25%"，却在"多端口状态串味、首帧 JIT 抖动、chunk 边界跳变、掉落乱动"上丢掉大量可避免的分数与信誉。

一句话押注：

> **在 CG-ZEST 的算法底座上，叠加 DPS-ZEST 系统层——「多端口共享-隔离托管织物」MSF、「端口级可靠性与确定性推理」DR、「接口级安全盾与恢复」ISS/SRP，并把"可部署约束"前移成训练目标（部署约束感知训练 DA-Train）。让系统在"N 台真机、逐帧被调用"的真实规则下，既稳（延迟方差小、可复现）、又省（单份权重服务 N 端口）、又安全（不越限、不跳变、掉落先回安全位）。**

三个可验证创新点：

1. **多端口共享-隔离托管织物 MSF（Multi-port Serving Fabric）**：官方要求暴露 **N 个连续端口 `8765..8765+N-1`**，端口数必须恰好等于机器人台数 N，且**每个端口都要独立、可靠地跑完整个交互流程**；共享模型时还需自行处理**并发**与**状态隔离**。MSF = 单份只读权重 + 显式 `EpisodeContext` 会话状态外置 + 连续批处理（continuous batching，max-wait ~2–5 ms）+ CUDA Graph/`torch.compile` 预热 + 端口看门狗与 last-good-chunk 回退。目标：显存 O(1) 而非 O(N)，p99 延迟稳定，端口间零状态串味。

2. **可靠性与确定性推理 DR（Dependability & Reproducibility）**：为对齐 §6 的"延迟方差 + 动作统计规律性"，加入 ① 确定性推理（固定 seed/关闭 dropout/确定性算子），使同一 (port, step, obs) 产生同一动作，可离线回放复现；② 时间集成动作块（TC-Ensemble）消除 chunk 边界跳变；③ 在线分布漂移监测（TTS-Monitor）用**视觉嵌入漂移 + 本体跟踪残差**（而非不存在的力觉）在线估计 5 类泛化场景（位置/干扰物/背景/未见物/人为干扰）下的失配，驱动保守化。

3. **接口级安全盾与安全恢复 ISS/SRP（Interface Safety Shield / Safe Recovery）**：动作在返回前经硬约束投影——关节限位、速度/加速度/加加速度上限、笛卡尔工作空间盒、双臂自碰撞距离、夹爪开度/夹持范围、chunk 间一阶/二阶连续性；非法动作**投影到最近安全动作而非置零**；检测到人为干扰（命令 vs 实际关节残差）时进入柔顺/暂停；抓取失败或掉落后执行**安全默认行为字典**（hold/retract/retry/ask），杜绝"随机乱动"。

三个词怎么落地：

| 词 | 落地 | 不做什么 |
|---|---|---|
| **可靠性** | MSF 的 p99 延迟治理 + 确定性推理/回放 + TC-Ensemble 消 chunk 跳变 + TTS-Monitor 在线失配监测 | 不追求"偶发最高成功率"；不允许延迟长尾；不靠随机采样制造动作多样性噪声 |
| **多端口部署** | 单权重共享 + EpisodeContext 状态外置 + 并发合批 + 端口看门狗；端口数 = N 精确对齐 | 不做"N 进程各拷一份权重"的显存浪费；不做裸共享可变模型实例（会状态串味） |
| **安全交互** | 接口级安全盾（投影而非截断）+ 本体残差干扰检测 + 安全默认行为恢复 + 训练期安全约束 | 不把安全全甩给底层控制器；不做"失败后乱动"；不做动作用零填充 |

## 2. 研究日志：从「算法性能」到「可托管评测系统」的认知转变

### 2.1 第 21 轮遗留的三个"系统层盲区"

```text
S1. 部署盲区：CG-ZEST 全篇没有出现"端口""并发""状态隔离""延迟方差"。
    而赛制要求 N 端口并发、逐帧调用、延迟入账——再好的模型，
    若首帧 JIT 抖动 500ms、端口间 BN/缓存串味，也会被判低可信度。
S2. 复现盲区：CG-ZEST 的 AC-SYNTH 每次采样带随机流噪声，随机性强；
    §6 要看"动作统计规律性"，而随机生成恰是"统计不规整"的来源。
S3. 安全盲区：CG-ZEST 的"安全包络"只是 clip；真机上 chunk 边界跳变、
    掉落乱动、自碰撞才是事故主因；且它假设的力觉安全监测并不存在。
```

### 2.2 三个新判断

1. **多端口不是"运维细节"，是"模型架构的一部分"**：把"每个 episode 的状态"从模型对象里彻底抽出成 `EpisodeContext`（观测历史、语言嵌入、动作块缓存、去噪噪声 seed、迟滞状态、CN/BN 运行量），才能安全共享权重。这样"多端口部署"从负担变成优势——**单份权重 + 会话外置 = 显存 O(1) + 状态零串味**。
2. **可靠性 = 可复现性 + 延迟稳定性 + 统计规整性三者之和**，且都可被 §6 观测。确定性推理不仅"看起来稳"，还让失败可离线归因、可迭代——这是长跑竞赛的复利。
3. **安全交互的第一现场是"接口"，不是"控制器"**：policy 的输出直接进入真机执行，底层来不及拦截"语义级"的坏动作（如双臂对撞、把易碎物往桌沿推）。因此**接口级安全盾**是最后一道、也是最可控的一道防线；而由于无力觉，"人为干扰检测"只能靠**命令 vs 实际关节的本体残差**。

### 2.3 与第 21 轮的关系：保留、升级、剪枝

| 层 | 第 21 轮 CG-ZEST | 第 22 轮 DPS-ZEST |
|---|---|---|
| 传感器假设 | 视觉+本体+**力觉+触觉** | **剪掉力觉/触觉**，改为视觉+本体+语言（符合真实目录） |
| 物体声纹 OD-CLONE | 戳/推/提/摇/捏五原语激励物理参数 | **降级/剪枝**：无触觉下"5 秒探测识别隐藏物理参数"不可证伪且风险高，改为**任务中在线物体表征修正**（视觉嵌入 + 执行残差） |
| 慢专家 | 云端 VLA 升级（外部通道） | **改为 policy 内多专家/多次采样**（同一延迟预算内），并用确定性种子绑定 |
| 延迟分层 | 假设可自由分层 | **对齐真实**：总延迟即 websocket 往返 + 推理，§6 入账 |
| 数据 | 仿真程序化物体 + 主动采集 | **保留**但接地到官方 32 任务 LeRobot 数据 + UnifoLM-WMA-0 世界模型做仿真增广 |
| 多端口 | 无 | **新增 MSF**（本轮核心） |
| 安全 | clip 安全包络 | **升级为 ISS 投影盾 + SRP 安全恢复 + 干扰检测** |
| 优化目标 | 成功率 | **成功率 + 步骤分 + §6 可信度（延迟方差/动作规整）** |

**剪枝清单（明确放弃）**：力觉/触觉输入；云端独立专家通道；5 秒无损物体物理参数辨识；把"随机采样多样性"当作不确定性来源（在 §6 下反而是噪声源，改为固定种子 + 几何一致性检验）。

## 3. 系统设计：DPS-ZEST

### 3.1 多端口共享-隔离托管织物 MSF

```text
         ┌──────────────────── SharedPolicyCore（单份只读权重, GPU） ───────────────────┐
         │  视觉编码器 / VLA 骨干 / 动作头   —— 权重只读、无可变运行态                    │
         └───────────────▲───────────────────────────────▲──────────────────────────────┘
                         │  batch of (ctx_id, obs_t)      │
   ┌─────────── 连续批处理调度器（max-wait 2–5 ms，按端口轮询） ─────────────┐
   │  聚合各端口 get_action → 一次 GPU 前向 → 拆分回各端口                    │
   └───▲───────────────▲───────────────────────────────▲──────────────────────┘
       │               │                               │
 ┌───────────┐   ┌───────────┐                    ┌───────────┐
 │ Port 8765 │   │ Port 8766 │   …… 恰 N 个 ……     │ Port 8765+N-1 │
 │ EpisodeCtx│   │ EpisodeCtx│                    │ EpisodeCtx│
 │ ws endpoint│  │ ws endpoint│                   │ ws endpoint│
 └─────┬─────┘   └─────┬─────┘                    └─────┬─────┘
   Robot 1          Robot 2                          Robot N
```

- **EpisodeContext（状态外置）**：`obs_history`、`lang_embed`、`action_chunk_cache`、`noise_seed`、`hysteresis`、`last_good_chunk`、`drift_stats`。所有可变状态都在这里，按连接/端口索引；`reset()` 只清本端口上下文。
- **连续批处理**：N 个端口的请求在一个 max-wait 窗口内合批；单端口独享时窗口取 0（不引入额外延迟），多端口并发时以极小排队换吞吐与稳定。
- **预热**：握手前对每个端口跑 `torch.compile`/CUDA Graph pin + 若干 dummy 前向，消除首帧抖动（§6 首步延迟很可能被单独统计）。
- **端口看门狗**：单端口推理超预算 → 返回 `last_good_chunk` 的平滑延续（TC-Ensemble 插值），不阻塞其他端口。

### 3.2 可靠性与确定性推理 DR

- **确定性**：`torch.use_deterministic_algorithms`、关闭 dropout、固定算子；每个 (port, step) 派生固定 seed（如 `seed = hash(port, episode_id, step)`），使 flow/diffusion 采样可复现。
- **TC-Ensemble（时间集成）**：每次 `get_action` 返回长度 T_a 的 chunk，但下一帧重新推理得到重叠 chunk；对重叠区间按指数权重平均，边界处保证 C⁰/C¹ 连续，消除跳变。
- **TTS-Monitor（免标签分布漂移监测）**：以训练集视觉嵌入的 kNN 距离衡量背景/未见物漂移；以 `‖a_cmd − q_actual‖` 本体残差衡量人为干扰/抓取滑移；用简单 EWMA + 阈值，超限时降低探索、切保守。

### 3.3 接口级安全盾与安全恢复 ISS/SRP

- **安全盾（投影而非截断）**：`a_safe = argmin_{a∈A_safe} ‖a − a_raw‖`，`A_safe` 由关节限位、速度/加速度/加加速度、工作空间盒、双臂间距、夹爪开度构成。用逐维 clip 作快速近似、必要时 QP 精投影。
- **干扰检测**：本体残差 `r_t = a_cmd,t − q_actual,t`；`‖r_t‖` 突增且方向与指令相反 → 判为外部扰动，进入柔顺（阻抗式降低刚度）或暂停。
- **安全恢复 SRP**：状态机 `{NORMAL, RECOVER}`；抓取失败/掉落后先回到安全位姿（retract）再重试；重试耗尽则 `HOLD`。给每个任务预置"安全默认行为"。

### 3.4 部署约束感知训练 DA-Train（把接口工程前移为训练目标）

在行为克隆/流匹配损失之外加入：① **边界连续性正则**（相邻 chunk 重叠区的一阶差）；② **安全可行性惩罚**（采样期对越限动作负奖励/可微投影近似）；③ **延迟友好正则**（偏好少数步采样、鼓励 KV/特征复用）；④ **端口无关不变性**（训练时随机打乱 batch 内 episode 组合，模拟合批，避免对 batch 组成的隐式依赖）。这是把"多端口/安全/延迟"从运行时补丁升格为模型先验的差异点。

**"三词的系统层"可能被误当成"与算法无关的工程配角"而在选题时被低估；更重要的是，"多端口状态隔离"与"§6 延迟/动作统计"都建立在 README 的文字规则上，而规则手册（Feishu）正文未能抓取、N 的真实取值与榜单分档均未公布——若实际评测对延迟的要求远比预期宽松、或 N=1，则 MSF 的边际收益大幅缩水，本轮的核心押注需要重新加权。** 缓解：把 MSF 设计成"可退化为单端口单例"的架构（无论 N 是多少都不吃亏），并优先实现 I1/I2/I4 这三个"无论如何都对"的组件。

# 第 22 轮产物 · DEPENDABLE-PORTS-SAFETY-ZEST (DPS-ZEST) 技术报告

> 检索日期：2026-11-06；来源见文末。本报告对第 21 轮 CG-ZEST 做**接地校正 + 系统层叠加**：剪掉不存在的力觉/触觉与云端专家通道，新增「多端口共享-隔离托管 MSF」「可靠性与确定性推理 DR」「接口级安全盾与恢复 ISS/SRP」，并把部署约束前移为训练目标 DA-Train。

## 0. 结论

在真实赛制（单模型 + N 端口真机并发 + 逐帧调用 + 延迟/动作统计入账）下，DPS-ZEST 主张：**先把"可托管、可复现、可安全交互"做成系统底座，再谈成功率**。核心三件套：

1. **MSF（多端口共享-隔离托管）**：单份只读权重 + 显式 `EpisodeContext` + 连续批处理 + 预热 + 看门狗；显存 O(1)，端口间状态零串味，端口数精确等于 N（8765..8765+N-1）。
2. **DR（可靠性与确定性推理）**：确定性 seed + 离线回放；TC-Ensemble 消 chunk 边界跳变；TTS-Monitor 用视觉嵌入 kNN + 本体残差在线估计分布漂移。
3. **ISS/SRP（接口级安全盾与安全恢复）**：动作返回前投影到安全集（限位/速度/加速度/工作空间/臂间距/夹爪）；本体残差检测人为干扰；失败后进入安全默认行为状态机。

预期收益：将 §6 可信度相关指标（延迟 p50/p99、延迟方差、动作离群率、端口状态串味）从"隐患"变为"达标项"，同时以 DA-Train 把这些约束写进模型先验。

```python
    def __init__(self, joint_lo, joint_hi, vel_max, acc_max, ws_box,
                 arm_min_dist, grip_lo, grip_hi, dt):
        self.joint_lo, self.joint_hi = joint_lo, joint_hi

class TemporalEnsembler:
    def __init__(self, decay=0.5):
        self.buf = deque()                       # [(t_start, chunk, weight_base)]
        self.decay = decay

    def add(self, chunk, t_start):
        self.buf.append([t_start, chunk.copy()])

    def action_at(self, t):
        num = np.zeros_like(self.buf[-1][1][0]); den = 0.0
        for t_start, chunk in self.buf:
            i = t - t_start
            if 0 <= i < len(chunk):
                w = np.exp(-self.decay * i)
                num += w * chunk[i]; den += w
        out = num / max(den, 1e-6)
        # 强制一阶连续：对输出做边界处 jerk 限幅（可接 SafetyShield）
        return out

        "observation.images.cam_left_high": [240, 320],
        "observation.images.cam_right_high": [240, 320],
        "observation.images.cam_left_wrist": [128, 128],
        "observation.images.cam_right_wrist": [128, 128],
    }

    def __init__(self, core, shield, device="cuda"):
        self._token = os.environ["UNIBOT_SUBMISSION_TOKEN"]
        self._control_space = os.environ["UNIBOT_CONTROL_SPACE"]
        self.core, self.shield = core, shield

    @property
    def metadata(self):
        return {
            "control_space": self._control_space,
            "obs_delta_indices": {k: list(v) for k, v in self.OBS_DELTA_INDICES.items()},
            "image_resize": {k: list(v) for k, v in self.IMAGE_RESIZE.items()},
            "action_chunk_size": self.ACTION_CHUNK_SIZE,
            "token": self._token,
        }

    def get_action(self, obs):
        # 由 MultiPortPolicyService 注入的端口上下文完成：这里给出"逻辑"，
        # 真实执行在 _serve_port 内（保证端口隔离）。
        T = self.ACTION_CHUNK_SIZE
        action = {
            "meta.token": self._token,
            "action.left_gripper": np.zeros((T, 1), np.float32),
            "action.right_gripper": np.zeros((T, 1), np.float32),
            "action.pivot": np.zeros((T, 7), np.float32),
        }
        if self._control_space == "joint":
            action["action.left_arm"] = np.zeros((T, 7), np.float32)
            action["action.right_arm"] = np.zeros((T, 7), np.float32)
        else:
            action["action.left_ee_pose_gripper_base"] = np.zeros((T, 6), np.float32)
            action["action.right_ee_pose_gripper_base"] = np.zeros((T, 6), np.float32)
        return action

    def reset(self):
        return {"ok": True}
```

## 3. 安全恢复状态机 SRP

```text
NORMAL ──(抓取失败/掉落/本体残差异常)──▶ RECOVER
   ▲                                        │
   │  ◀──(retract 到安全位姿 + retry 成功)──┤
   │                                        │
   └──(重试耗尽 → HOLD)◀────────────────────┘

RECOVER 默认行为字典：
  retract : 双回到安全 home 位姿（离合桌面 15cm）
  retry   : 重新逼近抓取（最多 k 次）
  hold    : 保持静止，等待下一步指令
  ask     : 高不确定时进入保守等待（不适用于无人评测，保留接口）
PODR 干扰判据：‖a_cmd − q_actual‖ 的 EWMA 突增 (> η·baseline) 且方向与指令相反 → 柔顺/暂停
```

## 4. 部署约束感知训练 DA-Train

```text
L = L_BC/flow                         # 主行为克隆/流匹配损失
  + λ_b · L_boundary                  # 相邻 chunk 重叠区一阶差平方 -> 边界连续
  + λ_s · L_safety                    # 采样动作越限的软惩罚/可微投影近似
  + λ_l · L_latency                   # 偏好少数步采样 / 特征复用（可选）
  + λ_p · L_port_invariance           # 训练期随机打乱 batch 内 episode 组合，模拟合批
```

- 数据：官方 32 任务 LeRobot v3.0（32000 eps / 169h），统一到观测目录的子集键；语言条件多任务联合训练。
- 底座：UnifoLM-VLA-0 / π0 / GR00T 之一（**须先核实 CC BY-NC-SA 许可是否被赛事允许**）；WMA-0 作世界模型做仿真增广（对应被剪掉的"SIM-DISTILL"的可行替代）。

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| N 真实取值未知；若 N=1 则 MSF 收益缩水 | MSF 设计为可退化单端口单例；优先做 I1/I2/I4 等"无论如何都对"的组件 |
| 合批排队延迟抵消吞吐收益 | 单端口时 max-wait=0；并发时上限 2–5 ms 并测量 p99 |
| 安全投影把动作推离任务 | 投影只在越限时生效；用软惩罚（DA-Train）让模型少越限，减少硬投影干预 |
| 本体残差受跟踪误差/通信延迟污染 | 用基线与方向判据双阈；必要时结合视觉滑移线索 |
| 官方模型 CC BY-NC-SA 非商用限制 | **比赛前核实许可**；备选 π0/GR00T/自训 |
| 确定性算子拖慢推理 | 实测；仅对采样路径做确定性，编码器可放开 |
| Feishu 规则正文未抓取、榜单未发布 | 榜单发布即刻回填真实分档；优先适配"延迟稳定/动作规整"这类稳定规则 |
