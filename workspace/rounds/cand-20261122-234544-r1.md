# 第 4 轮（灵感驱动研究循环·新灵感组第 2 轮；本轮灵感：「大语言模型」×「视觉语言动作模型」）

> **基线**：第 3 轮产出 MetricVoiceGauge-NCD-HUTDH-v21 + IP-425–430（语义-合规层 SDC/CAC/DCL/GIC/HPC+/CFC+；其上承 v20 联邦感知证书 PCA/CTS/CFC/HPC/CFCtrl 与 v19 证书体系 DCM/OGCC/CCV/DRS/OGC、v17 感知链 CLP/S2C/HCG/PSV/APS/AMC）。
> 本轮纪律：**生成模型只扩提议、不扩执行；语言是待验证的规格而非权威；VLA 是待认证的提议而非控制器**。不推倒 v21：SDC/CAC/DCL/GIC/HPC+/CFC+ 全部保留。本轮只做一件事：在 v21 的证书体系之外再套一层"生成式提议—确定性验证—运行时屏蔽"的信任不对称架构，把 LLM 变成可验证的规格编译器、把 VLA 变成带 conformal 管的提议生成器，并让二者在结构上都无法越过 v21 的证书门。

## 0. 直觉与动机

**灵感 1（大语言模型 → 语言作为"待验证的规格"，而不是控制器）**
直觉：v21 的规则库 R 是手写的，无法承接人类一句"把红箱子搬到门口，别碰人，等人让开再走"；而 LLM 恰好擅长把自然语言翻译成结构化表示，却也是"幻觉机器"。关键反转：**不要因为 LLM 说得流利就赋予它权威**。把 LLM 当成"编译器前端"——它只产出候选的形式化规格（义务逻辑规则、目标谓词、任务图、假设集），再由一个确定性验证器做"类型检查 + 意义契约 + 安全单调性检查 + 一致性检查"；只有通过验证的规格才进入 v21 的 R。类比"LLM 写代码、证明器验代码"：LLM 负责猜，验证器负责判。核心创新：**神经-符号规格编译器 (Neural-Symbolic Specification Compiler, NSSC)** 与**意义契约 (Meaning Contract)**：我们从不宣称 LLM"理解了"意图，只宣称编译出的规格在一组有限行为场景契约 M 上可复现地符合；残余歧义被显式表示为 **deontic conformal 集 Γ_R(u)**，并按 v21 的非对称门槛处理——**增强安全的解释低门槛接受，削弱安全（许可/解锁）的解释高门槛 + 人工确认**。这把 P36 从"手势意图"推广到"语言意图"。

**灵感 2（视觉语言动作模型 → 端到端策略作为"待认证的提议生成器"）**
直觉：VLA 把视觉+语言直接映射为动作块 a_{t:t+H}，通用、平滑、可语言条件化，但不可验证、可能幻觉，且**端到端恰恰抹掉了证书可以附着的中间表示**。关键反转：**VLA 的端到端性应被视为负债而非资产**。我们不把 VLA 当控制器，而当"提议生成器"：VLA 产出动作块，经 **conformal 动作管 (conformal action tube)** 把轨迹误差膨胀成以 ≥1-α_tube 覆盖真实执行轨迹的管，再经**再符号化 (re-symbolization)** 投影到 v21 可认证的符号计划表示（路点/技能序列），最后交给 v21 的 HPC+ 门与 DCL 过滤器。**VLA 提议，证书裁决**：安全时执行前缀；不安全时做**最小干预投影**到最大可认证安全子集；投影代价过大或安全集为空则回退到 v21 认证规划器或 SafeStop。无法再符号化的 VLA 输出一律不可执行。核心创新：**认证 VLA 屏蔽器 (Certified VLA Shield, CVS)**——用"管膨胀"把 VLA 不确定性变成像 CertBox 一样可认证的鲁棒性裕度。

**二者如何统一：提议—验证—屏蔽 (Propose–Verify–Shield, PVS) 与信任不对称**
统一为 v21 证书体系之外的**生成式提议层**：LLM 在慢车道（~1Hz）产出规格/目标候选，VLA 在中车道（~10Hz）产出动作块候选，v21 证书门在快车道（50Hz）裁决。共享状态 ζ_fed/ζ_sem 扩展为 **ζ_gen = ζ_sem ∪ (Π, Q, Prov, Γ_R, Tube, g_state')**。核心不变量（**信任不对称律**）：对任意生成模型 G，`Exec_v22 = Exec_v21 ∩ Shield(G) ⊆ Exec_v21`——生成模型只能**扩大提议空间 Π**，永远不能**扩大执行集**。证书是唯一的信任边界；生成式产物一律携带**出处信封 (provenance envelope)** 与验证记录，未验证即隔离 (quarantine)。LLM 还能把证书翻译成人话做审计，但**只能引用证书字段、不得新增事实**——解释是证书的投影，不是证书的来源。

## 2. 设计原则（在 P34–P36 基础上新增 P37–P39）

**P37 提议—执行分离律（Proposal–Execution Separation / Trust Asymmetry）**
对任意生成模型 G（LLM 或 VLA），`Exec_v22 = Exec_v21 ∩ Shield(G) ⊆ Exec_v21`。G 只能向提议空间 Π 增补候选，执行集恒为"候选 ∩ 已认证安全集"。任何生成式产物不得绕过证书门；Shield 失效或生成式产物不可验证时，回退到 v21（再退 v20/v19/v18）。生成模型的"能力"只体现为 Π 的丰富度，不体现为执行权限。

**P38 可验证规格律（Verified Specification）**
LLM 输出一律视为不可信提议。只有同时通过 (a) 语法/类型检查、(b) 意义契约 M 的行为一致性、(c) **安全单调性检查**（不得削弱已有 F 规则；任何 P 规则只能解除 DCL 自身限制）、(d) 与现有规则库的一致性检查 的规格，才允许进入 R。语言理解永不被假设成立；歧义表示为 conformal 集 Γ_R(u)，按非对称门槛处置：**增强安全的解释 θ_low 即接受，削弱安全的解释需 θ_high + 人工确认**。

**P39 再符号化律（Re-symbolization before Certification）**
VLA 动作块必须先经 σ 投影到 v21 可认证的符号计划表示，并膨胀为 conformal 动作管 Tube(τ_A, ρ_VLA)，才能进入 HPC+ 与 DCL；不可再符号化或管过胖（不确定性过高）的输出视为不可执行，直接回退。不确定性只允许被"膨胀进安全裕度"，不允许被"忽略进执行"。

## 3. 与基线的接口（如何退化）

- NSSC 失效（LLM 不可用/验证器崩溃）⇒ 规则库冻结在上一已验证版本，指令退回人工/模板化解析 ⇒ 等价 v21；
- 规格验证不通过 ⇒ 该指令不进入 R，触发澄清或最严默认 ⇒ 执行集不增；
- CVS 失效（VLA 不可用/管不可标定）⇒ 回退 v21 认证规划器 ⇒ 等价 v21；
- 再符号化失败 / 管过胖 ⇒ 该动作块不可执行 ⇒ 回退；
- LGC 失效 ⇒ 目标歧义按最严解释（不移动/最小动作）⇒ 子集；
- TLO/CCG 失效 ⇒ 生成式产物全部隔离，只用 v21 证书链 ⇒ 等价 v21；
- 全部失效 ⇒ 完全回退 v21 ⇒ `Exec_v22 ⊆ Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19 ⊆ Exec_v18`（引理 168）。
- **安全继承**：LLM 只进已验证规则（P38）、VLA 只进已认证管（P39）、Shield 只做交与投影、所有回退向 v21 收敛。三车道以事件方式接入 APS 新鲜度阶梯，控制路径仅 O(1) 查询。

## 4. 预期贡献

1. **信任不对称的 PVS 架构**：首次给出"生成模型只扩提议、不扩执行"的形式化不变量与安全继承证明，使 LLM/VLA 能在不牺牲证书保证的前提下进入安全关键系统；

## 5. 本轮最大风险

**一句话**：整个生成式层的安全最终押在"验证器/意义契约"这个新的信任根上——LLM 可以产出形式上通过类型检查与有限意义契约、却在语义上背离真实意图的规格（specification gaming），VLA 可以产出通过 conformal 管却在标定分布外执行的动作，于是系统会**"字面上验证通过、精神上南辕北辙"**，把 v21 的"合规的缺席幻觉"升级为"可验证的意图幻觉"。

# IP-431 神经-符号规格编译器：LLM 猜，验证器判
class NeuralSymbolicSpecCompiler:
    def __init__(self, llm, verifier, meaning_contract, rule_base,
                 theta_low=0.5, theta_high=0.9, alpha_contract=0.01, k=8):
        self.llm = llm                              # 语法约束解码，保证可解析
        self.V = verifier                           # V_type/V_contract/V_mono/V_cons
        self.M = meaning_contract                   # 有限行为场景契约
        self.rules = rule_base                      # v21 版本化规则库（merkle 锚定）
        self.theta_low, self.theta_high = theta_low, theta_high
        self.alpha = alpha_contract
        self.k = k

    def compile(self, u, context):
        cands = self.llm.sample_grammar_constrained(u, context, k=self.k,
                                                    grammar=DEONTIC_DSL)
        scored = []
        for spec in cands:
            if not self.V.type_ok(spec):                 continue
            if not self.V.consistent(spec, self.rules):  continue
            if not self.V.safety_monotone(spec, self.rules):  # 不得削弱 F（P38c）
                continue
            score = self.V.conformance(spec, self.M)     # 在 M 上的行为一致度
            scored.append((spec, score))
        gamma = conformal_filter(scored, alpha=self.alpha)   # Γ_R(u)
        return gamma

    def accept(self, gamma, direction, human_ok=False):
        # 非对称门槛（P38）：增强安全低门槛，削弱安全高门槛 + 人工确认
        if direction == "SAFETY_INCREASING":
            spec = argmax_score(gamma)
            return spec if spec.score >= self.theta_low else None
        if direction == "SAFETY_DECREASING":
            if len(gamma) == 1 and gamma[0].score >= self.theta_high and human_ok:
                return gamma[0]
            return None
        return None       # 歧义 → 澄清 / 最严默认

    def commit(self, spec):
        """只有已接受规格才进 R；版本 + merkle 锚定（复用 v21 审计链）"""
        return self.rules.commit_verified(spec, provenance=Prov(spec))


# IP-432 认证 VLA 屏蔽器：VLA 提议，证书裁决
class CertifiedVLAShield:
    def __init__(self, vla, dynamics, shield_v21, conformal,
                 alpha_tube=0.01, d_max=0.3):
        self.vla = vla
        self.f = dynamics
        self.shield21 = shield_v21          # v21 HPC+ ∧ DCL
        self.calib = conformal
        self.alpha_tube = alpha_tube
        self.d_max = d_max

    def propose(self, obs, u):
        chunk = self.vla.act(obs, u)                    # A_{t:t+H}
        rho = self.calib.trajectory_quantile(chunk, alpha=self.alpha_tube)
        tau = rollout(self.f, obs, chunk)               # τ_A
        return chunk, inflate_tube(tau, rho)            # Tube(τ_A, ρ_VLA)

    def shield(self, chunk, tube):
        sym = resymbolize(chunk)                        # σ: A → W ∪ {⊥}
        if sym is None:
            return self.fallback("UNRESYMBOLIZABLE")    # P39：不可再符号化→不可执行
        if self.shield21.certifies(tube, sym):          # 管级认证（引理 166）
            return chunk[:self.shield21.safe_prefix_len]
        a_star, cost = project_to_safe(chunk, self.shield21.safe_set(),
                                       metric=d)        # 最小干预投影
        if a_star is None or cost > self.d_max:
            return self.fallback("PROJECTION_TOO_EXPENSIVE")
        return a_star

    def fallback(self, reason):

# IP-433 语言接地证书：目标歧义→conformal 集；语音=在场证据
class LanguageGroundingCertificate:

# IP-436 三车道编排：慢思考 / 中提议 / 快裁决
class TrustLaneOrchestrator:
    def __init__(self, aps, nssc, cvs, ttl_gen=1.0):
        self.aps = aps                  # v17 APS 新鲜度阶梯
        self.nssc, self.cvs = nssc, cvs
        self.ttl = ttl_gen
        self.state = {"spec": None, "chunk": None, "ts": {"spec": 0, "chunk": 0}}

    def tick(self, now, obs, u, human_ok=False):
        # 慢车道：规格编译（事件化，非每帧）
        if now - self.state["ts"]["spec"] >= 1.0:
            gamma = self.nssc.compile(u, obs.context)
            spec = self.nssc.accept(gamma, direction=classify_direction(gamma),
                                    human_ok=human_ok)
            self.state["spec"] = spec
            self.state["ts"]["spec"] = now
        # 中车道：VLA 提议（带 TTL，过期即丢弃）
        if now - self.state["ts"]["chunk"] >= 0.1:
            chunk, tube = self.cvs.propose(obs, u)
            self.state["chunk"] = (chunk, tube)
            self.state["ts"]["chunk"] = now
        if now - self.state["ts"]["chunk"] > self.ttl:
            self.state["chunk"] = None                    # 过期 → 回退 v21
        # 快车道：只做 O(1) 状态查询 + 证书门
        return self.state

## 3. 推导

**引理 163（提议—执行分离）** 设 Shield 实现为"候选 ∩ 已认证安全集，并对不可认证候选回退 v21"。则对任意生成模型 G，`Exec_v22 = Exec_v21 ∩ Shield(Π_G) ⊆ Exec_v21`。故 G 的表达能力与安全继承解耦：G 变强只会让 Π 变大，不会让执行集越界；G 输出不可验证时，交集为空、回退 v21。∎

**引理 164（规格编译的保守性）** NSSC 只接纳通过 (a) 类型、(b) 意义契约、(c) 安全单调、(d) 一致性检查的规格。安全单调检查禁止削弱既有 F 规则；P 规则仅解除 DCL 自身限制（沿用 v21 P35）。设规则库由 R_old 更新为 R_new，则对任意计划集 `Exec(R_new) ⊆ Exec(R_old)`，除非存在经人工确认的显式安全削弱授权（该授权本身是一张可审计的 P 证书）。故 LLM 无法单方面扩大执行域。∎

**引理 165（意义契约的覆盖界及其边界）** 若校准场景 (σ_i, y_i) 与真实意图分布可交换、|M_cal| = n，则 conformal 集满足 `P(y_new ∈ Γ_R(u)) ≥ 1−α_contract`。但该保证是相对 **M 所刻画的意图**，不是相对"说话者脑中的意图"。若 M 未覆盖某类语义（否定、条件、指代、方言、隐含前提），覆盖率保证对真实意图失效——这正是本轮最大风险的形式化落点：κ_contract 只度量 M 的覆盖，不度量 M 的完备。∎

**引理 166（VLA 管的鲁棒安全）** 若 conformal 标定给出 `P(‖τ_actual − τ_A‖ ≤ ρ_VLA) ≥ 1−α_tube`，且膨胀管 Tube(τ_A, ρ_VLA) 与 Obs_t 无碰撞并满足 DCL 过滤，则真实执行轨迹无碰撞的概率 ≥ 1−α_tube。若管不可认证（过胖/无标定），CVS 回退，回退路径 ⊆ v21（引理 163）。∎

**引理 167（最小干预投影的有界性）** 设安全集 S_cert 非空、d(·,·) 为动作块空间上的度量。若 `d(A, S_cert) ≤ d_max`，则 Proj_Safe(A) 存在，且对 VLA 提议的修改量有界；若 `d(A, S_cert) > d_max` 或 S_cert = ∅，则 CVS 回退认证规划器/SafeStop。故"VLA 提议、证书裁决"不会退化为"VLA 悄悄接管"。∎

**引理 168（v22 整体安全继承）** 同一几何快照、规则库与机器人集合下：NSSC 只进已验证且单调安全的规格（164）、CVS 只执行管认证或投影安全的动作（166、167）、Shield 只做交与投影、所有失效回退 v21。故 `Exec_v22 = Exec_v21 ∩ Shield(Π) ⊆ Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19 ⊆ Exec_v18`。∎

**引理 169（接地解释的无新增事实性）** GAN 对每条生成主张 c 要求存在证书字段 f 使 `f ⊨ c`；否则整段解释拒发。故解释不引入证书之外的事实，审计者可由解释反查到证书：证书是解释的 **sound** 来源（不保证完备，可能漏说）。这抑制"流畅但无根据"的解释诱导的自动化偏见。∎

## 7. 已知风险与失效模式

1. **验证器/意义契约是新的信任根**（最大风险，见第 8 节）：M 只覆盖有限语义，LLM 可产出"形式通过、语义背离"的规格。缓解：对抗意义契约（E805）、分层 conformal、安全单调默认拒绝、人工确认削弱安全的解释。
2. **VLA 分布外执行**：conformal 管在标定分布外失效。缓解：管过胖即回退（P39）、在线漂移检测（E823）、观测一致性检查（E822）。
3. **规格 gaming / Goodhart**：LLM 优化"通过验证器"而非"符合意图"。缓解：M 与验证器不暴露给生成模型、独立红队、语义等价性检查、默认最严。
4. **三车道时序错配**：慢车道规则过期、动作块陈旧。缓解：TTL_gen + APS 新鲜度阶梯 + 中途重认证（E811、E829）。
5. **最小干预投影的可行性**：安全集为空或投影代价过大导致频繁回退、活性下降。缓解：d_max 自适应 + 认证规划器兜底（E808、E810）。
6. **自动化偏见与解释操纵**：流畅解释诱导操作员过信。缓解：GAN 逐主张接地 + 强制显示证书引用与不确定性（E818、E819）。
7. **隐私与数据治理**：LLM 处理指令/场景语义，VLA 处理视觉。缓解：本地推理、原始图像不出设备、只传证书/特征/出处哈希（沿用 v21 E794 并扩展）。
8. **能力与安全的耦合误判**：把"提议空间变大"误读为"执行权限变大"。缓解：P37 不变量形式化、Exec_v22 ⊆ Exec_v21 的运行时断言（E830）。

## 8. 本轮最大风险

**一句话**：整个生成式层的安全最终押在"验证器/意义契约"这个新的信任根上——LLM 可以产出形式上通过类型检查与有限意义契约、却在语义上背离真实意图的规格（specification gaming），VLA 可以产出通过 conformal 管却在标定分布外执行的动作，于是系统会**"字面上验证通过、精神上南辕北辙"**，把 v21 的"合规的缺席幻觉"升级为"可验证的意图幻觉"。
