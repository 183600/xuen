# 想法区 · 第 5 轮：贴边的证书，和一条零松弛的脊柱

**灵感词**：SMT solver / worst-case analysis / self-stabilizing algorithm
**起点**：v1.4「X-DUB/PACE-I*」。38 例（n=12–21）上 1,994 节点 / 0.104 s / 302 表；35/38 在根部闭合，只剩 3 例：hard3#2（602 节点）、hard3#5（1,336 节点）、large_het#1（21 节点）。v1.4 的判断是：这三例的 gap 是「序」，不是「量」。本轮要把这句话从诊断变成一个可检查的证书。

## 一、先把「量」彻底排除：三个残差在根部都是贴边，不是超载

我用正确的根状态（`r_i=est_i` 是优先图上的最长头，`d_i=h−q_i` 是最晚完成）重算了三例在 `h=OPT−1` 的根区间表。v1.4 的 MINT/PACK-SET 都没触发，不是因为它们「不够强」，而是因为根本没有区间超载：

| 实例 | n | h=OPT−1 | 根最小 slack | 贴边窗口 | 读法 |
|---|---:|---:|---:|---|---|
| hard3#2 | 12 | 28 | **0** | `[11,28]`，强制=51，cap=51 | 恰好填满，差一个「排不进去」 |
| hard3#5 | 14 | 38 | **1** | 多个单格窗口，强制=2，cap=3 | 差一个单位，任何区间都不超 |
| large_het#1 | 15 | 39 | **0** | `[26,27]`，强制=3，cap=3 | 三个任务各被强制收 1，恰好填满 |

这张表把本轮的方向定死了：**在这三例上，MINT/PACK-SET 的共同前提——某个窗口、某个窗口并、或某个装箱已经超——没有出现**。不是它们不够强，而是根上的量恰好贴边：单区间全过，两两并也全过（hard3#2 唯一的 disjoint tight 对 `[14,15]∪[18,19]` 是 W=4/cap=6），PACK-SET 也找不到坏装箱。要动的不是「量」，是「这些量能不能按优先序排进去」。

这也是对 v1.4 的一个补刀：v1.4 说「MINT/PACK-SET 不触发」，但没说「为什么不触发」。现在知道了：不是证书不够强，是**根上的区间系统已经紧到不能再紧**，超载只可能来自「紧窗口之间的整性拼接」，而不是某个窗口内部。

## 二、hard3#2 的解剖：一条零松弛脊柱，把问题变成「剩余装箱」

hard3#2 的根 `est/q` 给出：

```text
p    = [8, 3, 4, 9, 6, 5, 6, 3, 10, 2, 7, 2]
est  = [0, 8,11, 8,15,11,11,16,15,19,19,26]
q    = [20,17,10, 0, 0,12, 0, 9, 0, 0, 2, 0]
h    = 28
```

链 `C = 0→1→5→7→10→11` 的长度是 `8+3+5+3+7+2 = 28 = h`。这不是「一条普通的 critical path」，而是**零松弛脊柱**：对任意可行排程，设 `s_j` 是链上第 j 个任务的开始，

```text
h − q[last] ≥ s_q + p_q ≥ s_1 + Σp ≥ est[first] + Σp = h − q[last]
```

首尾都夹死，所以每个不等号都取等：`s_1=est[first]`，相邻任务之间零空隙。于是链上六个任务的块被完全钉死：

```text
0[0,8]  1[8,11]  5[11,16]  7[16,19]  10[19,26]  11[26,28]
```

再看贴边窗口 `[11,28]`：强制工作 `=51=cap`。因为总强制工作恰好等于容量，**每个任务都必须取到自己的最小重叠**；其中任务 3（`r=8,d=29,p=9`）在 `[11,28]` 上的最小重叠只在 `s=8` 取到，所以任务 3 被迫是 `[8,17]`。这一步不是「猜」，是「贴边等号 ⇒ 所有任务同时取最小值」的直接推论。

把链上落在 `[11,28]` 的四个块（5/7/10/11，共 17 个单位）和任务 3 的 `[11,17]`（6 个单位）从容量里扣掉：

```text
剩余容量 = 51 − 17 − 6 = 28
剩余任务（完全落在 [11,28] 内）= {2,4,6,8,9}
尺寸 = [4,6,6,10,2]，和 = 28
```

**剩余容量恰好等于剩余尺寸之和**。现在问题不再是「量够不够」，而是「这些整块能不能塞进被固定块切碎的自由区间」。取一个具体的机器分配：四个链块都在 M0（它们首尾相接，可以同机），任务 3 在 M1，M2 全空。自由区间是 `M1=[17,28]`（11）和 `M2=[11,28]`（17）。尺寸和 28 = 11+17，任何装箱都必须把两个箱子刚好填满；但 `{4,6,6,10,2}` 没有任何子集和为 11（4+6=10，4+6+2=12，6+6=12，10+2=12，……），所以这个分配不可能。其他分配把自由区间切得更碎，只会更难。枚举 `3^5=243` 个「固定块→机器」候选分配（剪掉资格不符/同机重叠），每个分配做一次精确装箱，**全部失败**。

这就是本轮的新证书：不是一条不等式，而是「一条零松弛脊柱 + 一个贴边窗口的唯一 argmin + 对全部机器分配的装箱反驳」。它的形状是**析取**（对每个分配都给一个反驳），不是线性的。

## 三、为什么「链式能量」本身不够：一个负结果

我一开始以为，只要把 v1.4 的 `β_i(S)` 换成「链约束下的最小重叠」就够了：

```text
γ_C(S) = min over 链上可行开始向量 Σ_j |[s_j,s_j+p_j] ∩ S|
```

因为 `min` 是带约束的，`γ_C(S) ≥ Σ_{i∈C} α_i(S)`，理论上可以多收「跨窗增益」。我在 hard3#2/#5、large_het#1 上枚举了全部链（109/155/146 条），对单区间和近紧区间对都算了 `γ_C(S) − Σα`，**最大增益是 0**。原因很朴素：这些链的每个任务本来就能在链约束下同时取到各自的最小重叠；链约束没有让谁多付。

所以本轮的关键不是「再加一条更强的能量不等式」，而是**换对象**：先利用零松弛把链钉死（这是纯序信息），再把剩余问题变成「固定块之间的装箱」（这是纯整性信息）。两者单独都不够，合起来才够。这个负结果也解释了为什么 v1.4 的 MINT 在 hard3#2 上 `mint_pairs=0`：它先贪心选了 `[11,28]`，把两个小 tight 窗都遮住了；我把所有 `slack≤1` 的窗口对单独试了一遍（例如 `[14,15]∪[18,19]`：W=4，cap=6），也没有一对超载。不是搜索漏了，是并本身不超。

## 四、SMT 视角：这是 DPLL(T) 的一次冲突，不是一条割平面

把本轮的做法翻译成 SMT 的语言：

- **理论传播（theory propagation）**：贴边窗口 `W` 的等号把所有任务的最小重叠锁死；某个任务的 `ArgMin` 是单点，就把它钉成等式 `s_i=t`。这正是 difference-logic 上的传播。
- **冲突（conflict）**：钉死之后，剩余问题是一个有限域 CSP——每个剩余任务选一个机器、一个开始时间，避开固定块。对它做**精确装箱反驳**（对每个机器分配，自由区间长度是箱子，任务是尺寸）。
- **证书（conflict clause）**：`NO-SOP(C,F,W,Φ,T)`，其中 `Φ` 是固定块到机器的全部分配，`T` 是每个分配下的装箱反驳。它不是「一个线性不等式」，而是「一族析取的反驳」；检查器要重放这族反驳，而不是代一个公式。

这也解释了为什么「最小核心」不收缩：我试了 `{2,4,6,8,9}` 的所有子集，只有全集不可行；冲突是五元的，没有一条两三元的小借口。SMT 里的 unsat core 在这里就是全五件——这不是实现没优化，是问题本身的结构。

## 五、self-stabilizing：证书是沿搜索路径的守恒量

本轮还有一个我没有预料到的理论收获。v1.4 的深度消融显示：MINT/PACK-SET 放到深度 2/4，**0 个新闭包**，时间 +11%。当时我把这解释成「整性间隙是全局的」。其实它是一条定理：

设 `σ0=(R0,A0,est0)`，`S` 是任意窗口并，`β_i^0=β_i^{σ0}(S)`，`cap0=cap^{σ0}(S)`，且 `Σβ^0>cap0`。沿任意 DEC 后代 `σ=(R,A,est)` 走，令 `D=R0\R` 是已排任务、`B_i` 是它们的实际块，定义

```text
L(σ) = Σ_{i∈D} |B_i ∩ S| + Σ_{i∈R} β_i^{σ}(S)
```

则 **`L(σ) > cap(σ)` 永远成立**。证明只用三件事：

1. 对剩余 `i`，`q_i(R)=q_i(R0)`（因为一个任务只有在其所有前驱都排完后才会被排，所以剩余任务的任何后继都不可能已被排），故 `d_i` 不变；而 `est_i` 只增不减，所以 `β_i^{σ} ≥ β_i^0`。
2. 对已排 `i`，它的块落在 `[est_i^0, d_i^0]` 内（DEC 边条件 + `q_i` 不变），所以 `|B_i∩S| ≥ β_i^0`。
3. `A_k` 只增不减，所以 `cap(σ) ≤ cap0`。

于是 `L(σ) ≥ Σβ^0 > cap0 ≥ cap(σ)`。**根上的一张 MINT 证书，沿整条路径自动保持有效，不需要在深处重算**。这正是「self-stabilizing」：证书是一个守恒量，排一个任务只是把它从 `β` 项搬到 `ov` 项，局部更新，不变量不破。PACK-SET 同理（已排块是 Ω 的一部分，剩余块只能更少，容量只会更小；任何完成都会诱导一个根上的装箱，矛盾）。

这条定理把 v1.4 的「只在根部」从工程选择升级为正确性结论；也说明 v1.5 不需要在深处跑 SOP——至少不需要为了「保住已有的证书」而跑。我在 5,485 个随机后代状态上验证了 `L>cap`，0 违反。

## 六、worst-case：这一层不是免费的

SOP 的残余装箱是精确的 bin packing，所以**根门在一般情况下是 NP-hard 的**（它包含 bin packing）。我不打算把它说成多项式证书。能说的是：

- 它只在根部、只在前面的 DEAD/INT/MINT/PACK-SET 都没闭时才跑；
- 指数只在 `|I|`（贴边窗口内、未被钉死的任务数）上；hard3#2 的 `|I|=5`；
- 实测 498 个装箱节点 / 8.9 ms，换来 602 个搜索节点；
- 最坏情况有 `nodecap=200000`，超了就返回 UNKNOWN，不剪，不影响正确性。

这是本轮对「worst-case analysis」的回应：新层的收益是真实的，但它的最坏情况是指数；它之所以可用，是因为门控把 `|I|` 压得很小，而不是因为算法有多项式保证。

## 八、负结果与一个正确性教训

1. **链式能量**：单区间和区间对上的最大增益都是 0；不是「没试出来」，是这三例的链约束不产生额外强制工作。
2. **slack-1 脊柱**：hard3#5 的临界链长 37，h=38，松弛 1；枚举 6 种「一个单位放哪」的脊柱排法，SOP 在 6/6 上都到 FIX（没有唯一 argmin 可钉），0 个闭包。large_het#1 同理（临界链长 38，h=39）。
3. **只做「容量相减」不够**：把固定块的占用从总容量里扣掉、只比较剩余尺寸之和，hard3#2 有 12 个「可行」的机器分配；必须做**按自由区间的装箱**才能否掉。
4. **最小核心是全五件**：`{2,4,6,8,9}` 的任何真子集都能装，只有全集不能；没有更短的解释。
5. **一个正确性教训（本轮最贵的）**：第一版残余搜索用「固定任务顺序 + 左移候选开始时间」的 DFS，1,332 节点就找到 hard3#2 的反驳，看起来又快又对。我用随机小实例和「全整数开始时间」的完整 DFS 对拍，**1,367 例里找到 5 个反例：full=YES，left=NO**。左移候选在固定顺序下不完备——它会漏掉「先放后面的任务、再回填前面」的排法。一个不完备的搜索返回 NO，就是假 NO。修复不是给左移打补丁，而是换成**容量剖面装箱**：忽略窗口内部的 r/d，只要求尺寸能装进自由区间长度；这是原问题的松弛，失败一定可靠，而且更快（498 节点 / 8.9 ms）。这条教训和 v1.4 的对称破缺 bug 是同一类：**admissible 的搜索不等于 sound 的证书**。
6. **hard3#5 / large_het#1**：SOP 完全不复用；它们的 gap 是 slack-1 的全局排序，不是零松弛脊柱。本轮没有工具。

## 九、一句话最大风险

**整个收益来自一个「脊柱恰好填满 h」的实例；两个残差都只有 1 单位松弛，SOP 的不动点在那里停住——如果真实负载的间隙是 slack-1 而不是 slack-0，v1.5 只多付一次根部链扫描，然后原样退回 v1.4 的 1,357 个节点。**

# 产物区 · v1.5：X-DUB/PACE-S*

> PACE-S = PACE with **S**pine / order certificates。在 v1.4 的 `INT`（单区间）、`MINT`（多窗口）、`PACK-SET`（装箱）之上，再加一层 **tier 1.4 `SOP`**（Saturation-Order Packing，饱和-订单装箱）：用零松弛优先链把任务钉死，再用贴边窗口的唯一 argmin 继续钉，最后对残余任务做「固定块 → 机器分配」的析取装箱反驳。
> 中文名：**脊柱-订单证书引擎**
> 状态：设计稿 + 可运行实现 + 38 例主实验 + 4,000 组根门对拍 + 1,000 组端到端暴力对拍 + 600 组 n=10–13 跨实现对拍 + 5,485 个后代状态的 carry 不变量验证 + 证书独立重放。1 个新根部闭包（hard3#2），2 个残差（hard3#5、large_het#1）。未接 PSPLIB，未做形式化验证，n≥22 未系统测试，未实现深部 SOP。

## 0. 版本关系与本轮增量

v1.4 的资产全部保留：`LC-PACK` 的 0/0.5/1/2/3 层、`LC-DEC`、`CHECK-LC`、`PROFILE` 的位并行与对偶池、`(est,A)` Pareto 前沿 `G`、孪生机器商 `CANON`、`FRONT`/`FRONT-SUB`/`NO-INT` 证书、`MINT`、`PACK-SET`。

本轮只加一层、证一个定理、给一个分离、补一个最坏情况：

1. **tier 1.4 `SOP`（饱和-订单装箱证书）**：在根部，先找一条零松弛优先链 `C`（`est[i1]+Σp+q[last]=h`），把它钉成固定块；再对贴边窗口 `W` 反复做「等号 ⇒ 唯一 argmin ⇒ 钉死」的饱和传播；最后把 `W` 内的剩余任务装进被固定块切碎的自由区间。对所有「固定块 → 机器」分配都装不下，就返回 `NO-SOP(C,F,W,Φ,T)`。
2. **carry 定理（self-stabilizing）**：根上的一张 `MINT`/`PACK-SET` 证书，沿任意 DEC 后代自动保持有效：把已排任务的 `β` 项换成它的实际重叠，不变量 `L>cap` 不破。这把 v1.4 的「只在根部」从工程选择升级为定理；也解释了深度消融的 0 新闭包。
3. **分离**：hard3#2 在 `h=OPT−1` 上，v1.4 的根 `INT`/`MINT`/`PACK-SET` 全部通过（`potential` 返回 `ok=True, wit=None`，`mint_pairs=0`），链式能量 `γ_C` 的最大增益为 0，而 `SOP` 返回 NO。所以 `SOP` 不是 v1.4 根层任何一条不等式的推论。
4. **worst-case**：`SOP` 的残余装箱是精确 bin packing，根门在一般情况下是 NP-hard 的；它只在根部、只在前面所有层都没闭时跑，指数只在 `|I|`（贴边窗口内未钉死的任务数）上。这是本轮对「新层不是免费午餐」的明确交代。

退化关系：

```text
关 SOP                                       → 逐字回到 v1.4 PACE-I
没有零松弛链                                  → SOP 返回 UNKNOWN（不剪）
只做容量相减、不做自由区间装箱                 → 弱化对照（hard3#2 有 12 个假可行分配）
忽略 W 内部的 r/d、只用自由区间长度做 bin packing → 本轮实现（可靠但偏弱）
```

## 1. 符号

| 符号 | 含义 |
|---|---|
| `I=(n,m,p,E,≺,h)` | 实例：加工时间、资格、优先图、期限 |
| `σ=(R,A,est)` | DEC 状态：未调度集、机器可用时刻、最早开始 |
| `q_i(R)` | i 到 R 内汇点的最长路（不含 `p_i`） |
| `r_i=est_i` | 释放时间 |
| `d_i=h−q_i(R)` | 最晚完成时间 |
| `C=(i_1,…,i_q)` | 一条优先链，`i_j≺i_{j+1}`（传递闭包） |
| `L_C=Σ_j p_{i_j}` | 链长 |
| `F` | 固定块集合，元素 `(i,s_i)`：任务 i 在任意可行排程中必须从 `s_i` 开始 |
| `W=[a,b]` | 一个时间窗口 |
| `ov(i,W)` | `|[s_i,s_i+p_i]∩W|`，固定块 i 在 W 内的占用 |
| `β_i(W)` | 非固定任务 i 在 W 内的最小重叠：`min_{s∈[r_i,d_i−p_i]} |[s,s+p_i]∩W|` |
| `ArgMin_i(W)` | 取到 `β_i(W)` 的全部整数开始时刻 |
| `slack_F(W)` | `m|W| − Σ_{f∈F} ov(f,W) − Σ_{i∉F} β_i(W)` |
| `O_W` | `{f∈F : |block_f∩W|>0}`，W 内正占用的固定块 |
| `Ω_W` | `{i∉F : r_i≥a, d_i≤b}`，完全落在 W 内、尚未固定的任务 |
| `φ:O_W→[m]` | 固定块到机器的分配（尊重资格、同机不重叠） |
| `free_k(W,φ)` | 机器 k 在 W 内、扣掉 φ 分配给它的固定块后的极大自由区间长度多重集 |
| `BinPack(S,B)` | 尺寸多重集 S 能否装进容量多重集 B（精确） |
| `D_m,D_p` | v1.4 的 MINT/PACK-SET 深度门（默认 0） |
| `SOP` | 本轮的 tier 1.4 根门 |

## 2. 形式定义

**定义 1（零松弛优先链 / 脊柱）**。链 `C=(i_1,…,i_q)` 满足 `i_j≺i_{j+1}`，且

```text
est[i_1] + Σ_{j=1..q} p_{i_j} + q_{i_q} = h.
```

**引理 1（脊柱钉死）**。若 C 是零松弛链，则任意可行排程中

```text
s_{i_1}=est[i_1],   s_{i_{j+1}}=s_{i_j}+p_{i_j},   s_{i_q}+p_{i_q}=h−q_{i_q}.
```

证明见 4.1。

**定义 2（固定块集）**。`F` 是若干 `(i,s_i)` 的集合。初始 `F` 由一条零松弛链的全部任务及其钉死开始时刻组成；之后由定义 4 的饱和传播扩充。

**定义 3（饱和 slack）**。对窗口 W 和固定块集 F：

```text
slack_F(W) = m|W| − Σ_{f∈F} ov(f,W) − Σ_{i∉F} β_i(W).
```

`slack_F(W)<0` 表示固定块 + 剩余任务的强制工作已经超过 W 的机器容量；`=0` 表示恰好填满。

**定义 4（饱和传播 / forcing）**。若 `slack_F(W)=0`，则任意可行排程中每个 `i∉F` 都必须取到 `β_i(W)`。若 `ArgMin_i(W)={s}` 是单点，就把 `(i,s)` 加入 F。重复直到没有新的单点 argmin，或出现 `slack<0`。

**定义 5（残余装箱实例）**。对 W 和 F：

```text
O_W = {f∈F : [s_f,s_f+p_f]∩W ≠ ∅}
Ω_W = {i∉F : r_i≥a, d_i≤b}
```

对每个合法分配 `φ:O_W→[m]`（`φ(f)∈E_f`；同机固定块不重叠），令 `free_k(W,φ)` 是机器 k 在 W 内挖掉 φ 分配给它的固定块后的极大自由区间长度。残余装箱问题是

```text
BinPack({p_i : i∈Ω_W}, ⋃_k free_k(W,φ)).
```

**定义 6（SOP 证书）**。

```text
CERT ::= ...                                   # v1.3/v1.4 全部节点
       | NO-SOP(C, F, W, Φ, T)                 # 脊柱-订单叶子
       | NO-RESOLVE(children)                  # 子节点全 NO
```

其中 `Φ` 是 `O_W` 到机器的全部合法分配，`T` 是每个 `φ∈Φ` 下的装箱反驳（或等价的、可由检查器重算的失败记录）。

**定义 7（SOP 检查器）**。

```text
CHECK-SOP(σ0,h,(C,F,W,Φ,T)):
  1 重算 est,q；验证 C 是零松弛链（逐边 ≺、长度、端点）
  2 由 C 重算固定开始；重放定义 4 的传播，要求得到的 F 与证书一致
  3 取证书给出的 W，重算 O_W/Ω_W（W 不必 slack=0；slack=0 只用于传播，
     残余装箱对任意窗口都可靠）
  4 枚举 O_W 的全部合法分配 φ；对每个 φ 重算 free_k(W,φ)
     重放 BinPack({p_i}_{i∈Ω_W}, ∪_k free_k(W,φ))，要求全部失败
  5 接受 iff 1–4 全过
```

实现中检查器是**重算式**的：它不信任证书里的 `Φ,T`，而是从 `(σ0,h,C,F,W)` 重跑同样的枚举与装箱；`Φ,T` 只是给人看的解释。

**定义 8（PACE-S 主程序）**。

```text
PACE-S(σ,h):
  1  if R=∅: return YES([])
  2  if DEAD(σ): return NO(DEAD)
  3  σ ← NORM(σ);  A* ← CANON_R(A);  estt ← (est_i)_{i∈R}
  4  if exact-memo[(R,A,est)]: return NO
  5  if ∃(est',A')∈G_{R,h}: est'≤estt ∧ A'≤A*: return NO(FRONT-SUB)
  6  (ok,φ,C,P,min_slack) ← INT(σ,h)          # v1.4 tier 1.25
  7  if ¬ok: return NO(NO-INT(...))
  8  if depth ≤ D_m ∧ |C|≥2:
  9      if MINT(C) returns (S,β,cap): return NO(NO-MINT(S,β,cap))
 10  if depth ≤ D_p ∧ min_slack ≤ 1:
 11      if PACKSET(P) returns cert: return NO(NO-PACKSET(cert))
 12  if depth=0 ∧ SOP_on:
 13      if SOP(σ,h) returns NO-SOP(C,F,W,Φ,T): return NO(NO-SOP(...))
 14  if ∃A'∈F_{R,h}: A'≤A*: return NO(FRONT)
 15  ok ← PO-LC-PACK(σ,h)                     # v1.2 的 0/0.5/1/2/3 层
 16  if ¬ok: exact-memo←h; F_INSERT; return NO(PACK)
 17  for child in CHILDREN(σ) sorted by slack:
 18      r ← PACE-S(child,h)
 19      if r=YES: return YES([(i,k,t)]+r)
 20  G_INSERT(R,h,(estt,A*)); exact-memo←h
 21  return NO(RESOLVE)
```

`SOP` 只放在第 12 步：在 DEAD/INT/MINT/PACK-SET 之后、搜索之前。这样 hard3#3 这类已被 MINT 闭的实例不会付 SOP 的钱；hard3#2 这种前面全过、又有零松弛链的实例才付。

**定义 9（SOP 子程序）**。

```text
SOP(σ,h):
  1  C ← FindSpine(σ,h)                       # 零松弛链，最多枚举 200 条
  2  if C=⊥: return UNKNOWN
  3  F ← {(i_j, est[i_1]+Σ_{l<j}p_{i_l})}
  4  repeat:
  5      for W in Windows(F):                  # r,d,固定块端点
  6          slack[W] ← m|W| − Σ_{f∈F}ov(f,W) − Σ_{i∉F}β_i(W)
  7      if min slack < 0: return NO-ENERGY
  8      if min slack = 0:
  9          for i∉F with |ArgMin_i(W)|=1: F ← F∪{(i,s)}
 10      until 没有新固定
 11  W* ← argmax_{slack[W]=0} Σ_{f∈F} ov(f,W)
 12  for φ in Assignments(O_{W*},m):
 13      if BinPack({p_i}_{i∈Ω_{W*}}, ⋃_k free_k(W*,φ)): return UNKNOWN
 14  return NO-SOP(C,F,W*,Φ,T)
```

## 3. 算法步骤与证书格式

### 3.1 找脊柱

1. 算 `est,q`（`po.heads_tails`）。
2. 对每个任务算 `slack_i=h−(est_i+p_i+q_i)`；只保留 `slack_i=0` 的任务。
3. 在零松弛任务上建「紧边」子图：`i→j` 当且仅当 `i≺j`、`est_j=est_i+p_i`、`q_i=p_j+q_j`。
4. 从没有紧入边的零松弛任务出发 DFS，枚举到汇点的路径，最多 200 条；每条都是零松弛链。

### 3.2 饱和传播

窗口端点取 `r_i`、`d_i`、`d_i−p_i`、`r_i+p_i`，再加上固定块的两端 `s_f`、`s_f+p_f`，以及 0 和 h。对每个窗口算 `slack_F(W)`；取最小 slack，负则 NO，零则把该窗口上所有单点 argmin 的任务钉死；重算窗口（因为固定块端点变多）；直到没有新钉死。

### 3.3 残余装箱

传播结束后，取「固定块占用最多」的 slack=0 窗口 `W*`。枚举 `O_{W*}` 的全部机器分配（`m^{|O|}`，剪掉资格不符和同机重叠）；对每个分配算每台机器的自由区间长度，把 `Ω_{W*}` 的尺寸做精确 bin packing。只要有一个分配能装下，就返回 UNKNOWN（不剪）；全部装不下才返回 NO。

### 3.4 证书长什么样

hard3#2 的证书（`h=28`）：

```text
C = (0,1,5,7,10,11)
F = {0→0, 1→8, 5→11, 7→16, 10→19, 11→26, 3→8}
W* = [11,28]
O_W = {5:[11,16], 7:[16,19], 10:[19,26], 11:[26,28], 3:[11,17]}
Ω_W = {2:4, 4:6, 6:6, 8:10, 9:2}     # 尺寸
cap = 51, 固定块占用 = 17+6 = 23, 剩余 = 28 = ΣΩ
对 3^5 = 243 个候选 φ（剪掉资格不符/同机重叠）：BinPack 全部失败；装箱搜索合计 498 节点
```

一个具体分配的解释：四个链块都在 M0，任务 3 在 M1，M2 全空；自由区间是 `M1=[17,28]`（11）和 `M2=[11,28]`（17）。`{4,6,6,10,2}` 没有任何子集和为 11，而总和 28=11+17 又迫使两个箱子都必须填满，所以这个分配失败。其他分配把自由区间切得更碎。

## 4. 定理与证明

### 4.1 脊柱钉死

**定理 1**。设 C 是零松弛链。任意可行排程中，C 的任务首尾相接，开始时刻如引理 1。

**证明**。设 `s_j` 是 `i_j` 的开始。由优先约束 `s_{j+1}≥s_j+p_{i_j}`，由释放 `s_1≥est[i_1]`，由期限/尾 `s_q+p_{i_q}≤h−q_{i_q}`。串起来：

```text
h−q_{i_q} ≥ s_q+p_{i_q} ≥ s_1+Σp ≥ est[i_1]+Σp = h−q_{i_q}.
```

首尾相等，故每个不等号取等；于是 `s_1=est[i_1]`，所有相邻空隙为 0。∎

### 4.2 饱和传播

**定理 2**。若 `slack_F(W)=0`，则任意可行排程中每个 `i∉F` 都取到 `β_i(W)`；若 `ArgMin_i(W)` 是单点 `{s}`，则 i 必须从 s 开始。

**证明**。固定块在任意可行排程中的位置就是 F 给的，故它们在 W 内的占用恰为 `Σ_{f∈F}ov(f,W)`。每个非固定 i 在 W 内的实际重叠 ≥`β_i(W)`，所以 W 内的总重叠 ≥ `Σ_F ov + Σβ = m|W|`（`slack=0`）。但 m 台机器在 W 内的总容量只有 `m|W|`，故总重叠必须恰好等于 `m|W|`，每个 i 都必须取等号；单点 argmin 即钉死。∎

**注**。这里没有假设固定块之间不重叠；若两个固定块在时间上重叠，它们必须上不同机器，`Σov` 仍然是把它们各自算一次，和 `m|W|` 的比较仍然可靠。

### 4.3 残余装箱

**定理 3**。若存在可行排程，则存在一个合法分配 `φ`，使得 `{p_i}_{i∈Ω_W}` 能装进 `⋃_k free_k(W,φ)`。

**证明**。取可行排程，把每个 `f∈O_W` 分配到它实际使用的机器，得到 φ（资格和同机不重叠自动满足）。每个 `i∈Ω_W` 满足 `r_i≥a`、`d_i≤b`，所以它的整块落在 W 内；它又不能与同机固定块重叠，所以整块落在该机器的一个极大自由区间内。把 i 分配给这个区间，得到装箱。∎

**推论 3.1**。若对所有合法 φ 都有 `BinPack` 失败，则 `FEAS(σ,h)=NO`。

### 4.4 SOP 可靠性

**定理 4**。若 `SOP` 返回 `NO-ENERGY` 或 `NO-SOP`，则 `FEAS(σ,h)=NO`。

**证明**。`NO-ENERGY` 由定理 2（`slack<0` 直接是强制工作 > 容量）。`NO-SOP` 由定理 1（脊柱钉死）+ 定理 2（传播钉死）+ 推论 3.1（残余装箱）复合而成：任意可行排程都会诱导一个 φ 和一个装箱，与「全部 φ 失败」矛盾。∎

### 4.5 carry 定理（self-stabilizing）

**定理 5**。设 `σ0=(R0,A0,est0)`，`S` 是窗口并，`β_i^0=β_i^{σ0}(S)`，`cap0=cap^{σ0}(S)`，且 `Σβ^0>cap0`。沿任意 DEC 后代 `σ=(R,A,est)`，令 `D=R0\R`，`B_i` 是已排任务的实际块，定义

```text
L(σ)=Σ_{i∈D}|B_i∩S| + Σ_{i∈R}β_i^{σ}(S).
```

则 `L(σ)>cap(σ)`。

**证明**。三个引理：

**(a) 对剩余 i，`q_i(R)=q_i(R0)`，故 `d_i^σ=d_i^0`，且 `est_i^σ≥est_i^0`，故 `β_i^σ≥β_i^0`。**
若 `j∈succ(i)` 已被排，则在 j 被排的那一刻 i 仍在 R 中且 i 是 j 的前驱，j 不可能 ready；矛盾。故 i 的所有后继都仍在 R，`q_i` 不变。`est` 的更新是 `max`，只增不减；可行开始区间 `[est_i,d_i−p_i]` 从左收缩，最小值只增。

**(b) 对已排 i，`B_i⊆[est_i^0,d_i^0]`，故 `|B_i∩S|≥β_i^0`。**
i 被排时 `t=max(A_k,est_i)≥est_i^0`；且 `t+p_i+q_i(R_at)≤h`。i 的后继在那一刻都还在 R（否则 i 不可能先于它们被排），故 `q_i(R_at)=q_i^0`，于是 `t+p_i≤h−q_i^0=d_i^0`。

**(c) `cap(σ)≤cap0`。** `A_k` 只增不减，`cap=Σ_k|S∩[A_k,∞)|` 只减不增。

由 (a)(b)，`L(σ)≥Σ_{i∈R0}β_i^0>cap0`；由 (c)，`>cap(σ)`。∎

**推论 5.1（MINT 不需要在深处重算）**。一旦根上的 MINT 证书触发，如果不在根上剪、继续下潜，任意后代状态都满足 `L>cap`；因此根上剪掉不会漏掉 YES。深处再跑 MINT 对「保住已有证书」没有增量，只可能发现**新的**、根上不存在的证书（v1.4 实测 0 个）。

**推论 5.2（PACK-SET 的持久性）**。若 `Ω0(a,b)` 在 σ0 装不进 `c_k=(b−max(a,A_k^0))_+`，则在任意后代也装不进：任何完成会把已排的 Ω0 块（由 (b) 仍在 `[a,b]` 内）和剩余的 Ω0 块一起放进 `[max(a,A_k^σ),b] ⊆ [max(a,A_k^0),b]`，从而诱导一个 σ0 的装箱，矛盾。

### 4.6 分离：SOP 不是 v1.4 根层的推论

**定理 6**。hard3#2 在 `h=OPT−1=28` 上满足 v1.4 根层全部判据（`min_interval_slack=0`，`potential` 返回 `ok=True, wit=None`，`mint_pairs=0`，PACK-SET 无反驳），但 `SOP` 返回 NO。因此 `SOP` 严格强于 v1.4 根层的并。

**证明**。前件由实现直接验证（见 6.4）；后件由定理 4。链式能量 `γ_C(S)−Σα` 在单区间和区间对上最大增益为 0（6.7），所以这个分离不是「链式能量」的推论，而是「脊柱钉死 + 饱和传播 + 残余装箱」的复合。∎

### 4.7 复杂度

**定理 7**。固定 m：

```text
FindSpine:      O(κ(n+m))，κ≤200
Propagate:      O(n · n² · n · h) = O(n⁴h)     # ≤n 轮，每轮 O(n²) 窗口，每窗口 O(nh)
CapacityPack:   O(m^{|O|} · (m+|O|)^{|I|})     # 全分配 × bin packing
```

`|O|≤n`、`|I|≤n`，所以根门最坏是指数的；它包含 bin packing，故一般情况 NP-hard。实测 hard3#2：`|O|=5`、`|I|=5`、498 个装箱节点、8.9 ms。PACE-S 的搜索部分与 v1.4 完全相同，SOP 只加一个根常数。

**读法**：v1.4 在根上 `potential` 返回 `ok=True, wit=None`，`min_interval_slack=0`；它不是「差一点被 INT 抓到」，而是「INT 已经贴边到不能再贴，剩下的是排不进去」。SOP 把 602 个搜索节点换成一条 7 个钉死任务 + 5 个尺寸 + 498 个装箱节点的证书。

### 6.4 正确性

| 测试 | 规模 | 结果 |
|---|---|---|
| 根门 `SOP` 与无剪枝暴力对拍（直接调 `root_gate`，h 扫 5 个值） | 4,000 例（n=5–10，m=2/3，含异构，种子 101，800×5） | **62 次 NO，0 次假 NO；62 张证书全部重放接受** |
| 端到端与无剪枝暴力对拍（`pace_sop` 全深度 MINT/PACKSET + SOP） | 1,000 例（n=5–9，m=2/3，h 扫 5 个值） | **0 不一致** |
| 与 v1.2 `sub` 对拍（root SOP） | 600 例（n=10–13，m=2/3，h 扫 5 个值） | **0 不一致** |
| `h=OPT` 假阳性 | 38 例 | **0 次误报** |
| carry 不变量 `L>cap` | 5,485 个随机后代状态（hard3#3/#10 的 MINT 证书） | **0 违反** |
| 证书独立重放 | hard3#2 的 `NO-SOP` | **0 无效** |
| v1.4 资产 | `FRONT`/`FRONT-SUB`/`NO-INT`/`NO-MINT`/`NO-PACKSET` | 未改动 |

**一个正确性教训（值得单独记下）**：第一版残余搜索用「固定任务顺序 + 左移候选开始时间」的 DFS，hard3#2 只要 1,332 节点，看起来又快又对。我用 1,367 个随机小实例和「全整数开始时间」的完整 DFS 对拍，找到 **5 个反例：full=YES，left=NO**。左移候选在固定顺序下不完备——它会漏掉「先放后面的任务、再回填前面」的排法。一个不完备的搜索返回 NO，就是假 NO。修复不是给左移打补丁，而是换成**容量剖面装箱**：忽略 W 内部的 r/d，只要求尺寸能装进自由区间长度；这是原问题的松弛，失败一定可靠，而且更快（498 节点 / 8.9 ms）。这和 v1.4 的对称破缺 bug 是同一类：**admissible 的搜索不等于 sound 的证书**。

### 6.5 carry 定理的实验

从 hard3#3 与 hard3#10 的根 MINT 证书出发（`S=[22,23]∪[28,31]`、`cap=12`；`S=[22,23]∪[26,27]`、`cap=6`），随机走 300 条 DEC 后代路径，每步检查：

```text
L = Σ_{已排} |B_i∩S| + Σ_{剩余} β_i^σ(S) > cap(σ)
```

共 5,485 个状态检查，0 违反；同时逐项验证 `β_i^σ≥β_i^0`，也 0 违反。这不是「再跑一遍 MINT」，而是「证书作为守恒量沿路径搬运」；它把 v1.4 的深度消融（深处 0 新闭包、时间 +11%）解释成定理，而不是经验。

### 6.6 易实例开销

60 个 `h=OPT+5` 的易实例（n=10–14，m=3，新采样）：

| 配置 | 节点 | 时间 | 相对 v1.2 |
|---|---:|---:|---:|
| v1.2 `sub` | 804 | 0.0345 s | 1.00× |
| v1.3 PACE | 788 | 0.1247 s | 3.61× |
| v1.4 PACE-I | 788 | 0.1265 s | 3.67× |
| v1.5 PACE-S | 788 | 0.1285 s | 3.72× |

新层额外开销约 **1.6%**（0.1265 → 0.1285，噪声内）：`h=OPT+5` 时通常没有零松弛脊柱，`FindSpine` 直接返回 ⊥；即使有，前面的 INT/MINT/PACK-SET 往往已经闭掉。对 v1.2 的 3.7× 是 v1.3 的 INT 在**每个节点**上付的钱，不是本轮新增的。

### 6.7 负结果

1. **链式能量**：`γ_C(S)=min` over 链约束开始向量的总重叠。枚举全部链（109/155/146 条），对单区间和近紧区间对计算 `γ_C(S)−Σα`，三例的最大增益都是 **0**。链约束没有产生额外强制工作；SOP 的强度不来自这里。
2. **slack-1 脊柱**：hard3#5 的临界链 `0→2→4→10→11` 长 37，h=38，松弛 1；穷举 6 种「一个单位放哪」的脊柱排法（`(0,8,16,18,27)`、`(0,8,16,18,28)`、`(0,8,16,19,28)`、`(0,8,17,19,28)`、`(0,9,17,19,28)`、`(1,9,17,19,28)`），SOP 在 6/6 上都到 FIX（最小 slack=1，没有唯一 argmin 可钉），**0 个闭包**。large_het#1 同理（临界链长 38，h=39，slack=1）。
3. **只做容量相减不够**：把固定块占用从总容量里扣掉、只比较剩余尺寸之和，hard3#2 有 **12 个**「可行」的机器分配；必须做按自由区间的装箱才能否掉。
4. **最小核心是全五件**：`{2,4,6,8,9}` 的任何真子集都能装，只有全集不能；没有两三元的小借口。
5. **左移候选不完备**：1,367 个随机小实例里 5 个反例（full=YES，left=NO）；已换成容量剖面装箱。
6. **深部 SOP 未实现**：v1.4 的深度消融说明 MINT/PACK-SET 深下去 0 新闭包；SOP 的深部版本需要把 `est/q` 换成状态的 `est/q(R)`，本轮没做，也不声称有收益。
7. **hard3#5 / large_het#1**：SOP 完全不触发；它们的 gap 是 slack-1 的全局排序，本轮没有工具。

## 8. 已知风险

1. **收益高度集中**：1,393 个节点里，601 个节点的削减来自 hard3#2 一个实例；其余 37 例各 1 个节点（或不变）。这不是「普遍加速」，是「一个脊柱恰好填满 h 的实例被一眼看穿」。
2. **只处理零松弛脊柱**：hard3#5、large_het#1 的临界链分别只有 1 单位松弛；SOP 在 6/6 个脊柱排法上都到 FIX，0 闭包。若真实负载的间隙是 slack-1，v1.5 只多付一次根部扫描。
3. **容量剖面装箱是松弛**：它忽略 W 内部的 r/d，只要求尺寸装进自由区间长度。它可能漏掉「尺寸总和够、但 r/d 让某些项放不进」的矛盾；精确放置会更强，但第一版的左移搜索被证明不完备，完整的整数搜索又太慢。本轮选择了「可靠但偏弱」。
4. **装箱是指数的**：`O(m^{|O|}(m+|O|)^{|I|})`，靠 `nodecap=200000` 兜底；窗口内自由项多时会返回 UNKNOWN（不剪），或变慢。
5. **脊柱枚举有 cap**：最多 200 条零松弛链；若一个实例有大量零松弛链，可能漏掉「唯一能导出矛盾」的那条。
6. **只做根部**：SOP 没有深部版本；v1.4 的深度消融不能直接外推到 SOP。深部 SOP 需要状态化的 `est/q(R)`，本轮未实现。
7. **没有形式化验证**：定理 1–7 是纸面证明 + 4,000 组根门对拍 + 1,000 组端到端 + 600 组跨实现 + 5,485 个 carry 状态；没有 Coq/Lean。
8. **`h=OPT−1` 是有意的压力测试**：差 1 个单位的整性超载会被放大；真实 RCPSP/PSPLIB 的间隙分布未必长这样。
9. **随机生成器偏差**：n≤21，m=2/3，未接 PSPLIB；`p∈[2,10]`、优先边随机，和真实负载的链结构/资格结构不同。
10. **时间常数是 Python 的**：0.090 s 与 0.104 s 的相对比例换 C 会变；节点比与建表比是确定性的，时间比不是。
11. **资格在装箱里被忽略**：`BinPack` 把所有自由区间对所有项开放，这是进一步松弛；对 hard3#2（全资格）无影响，对异构实例会偏弱。
12. **检查器是重算式**：`CHECK-SOP` 从 `(σ0,h,C,F,W)` 重跑枚举，不信任证书里的 `Φ,T`；这保证可靠性，但证书不是「一次可独立核对的证明树」，而是「可重放的搜索记录」。

## 9. 一句话最大风险

**整个收益来自一个「脊柱恰好填满 h」的实例；两个残差都只有 1 单位松弛，SOP 的不动点在那里停住——如果真实负载的间隙是 slack-1 而不是 slack-0，v1.5 只多付一次根部链扫描，然后原样退回 v1.4 的 1,357 个节点。**
