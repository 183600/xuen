# 第 1 轮（新灵感循环 v3：「数据配比」×「机器人基础模型」）—— 一个基础模型，一份配方：把 32 个任务当成一个受约束的数据投资组合

> 承接 v2（UIP-01′~15）。v2 把力气花在**推理期**：滚动验证、撤回检测、Gazebo 判分、块长调度。但所有这些机制都受同一个上限约束——**模型本身没见过的东西，验证器再聪明也补不出来**。本轮换到**训练期**：既然规则要求单模型多任务，真正的自由度不是"每个任务训一个策略"，而是"**一个基础模型 + 一份数据配方**"。两个灵感词正好咬合：**机器人基础模型**提供可迁移的动作先验（让一个任务的数据能给另一个任务付红利），**数据配比**决定这份先验把容量花在哪些任务、哪些计分步、哪些泛化轴上。一句话：**榜单不是 32 个任务的加法，而是一个受 5 条泛化轴约束的数据投资组合；配比就是策略。**

---

## 0. 直觉：四个反例，说明"均匀配比"为什么错

1. **均匀采样 ≠ 最优投资**。32 个任务各约 1000 条，均匀采样把同样的梯度预算给了一个已经 95% 成功率的任务和一个 5% 成功率的任务。榜单按平均成功率+步骤分排序，前者的边际收益接近零，后者可能是数量级更大。更细的是**计分步**：前一步失败，后面的步骤分根本拿不到；所以"给末步多数据"不一定对，**给"卡住后面所有步的那一步"多数据**才对。
2. **多给数据 ≠ 多给多样性**。机器人模仿学习的缩放律反复显示：**环境/物体多样性比每个格子的演示条数更重要**；每个环境/物体超过某个阈值后，再加演示几乎不涨（见 §2）。所以配方应先买**覆盖**（5 条泛化轴 × 32 任务），再买**深度**（同格子的条数）。
3. **一个基础模型 ≠ 32 个任务的平均**。共享骨干会带来正迁移（抓/放/插/折/拉链等技能复用），也会带来**负迁移与捷径学习**：如果某个任务的背景/物体位置太单一，模型会记住"桌布颜色"而不是"抓杯子"。配比因此有第二重身份——**正则化**：跨任务、跨轴的混合是在破坏捷径。
4. **接口也是分布**。评测端在握手时固定相机集合、图像缩放、时间堆叠与块长；训练时若只见过一种接口，评测换一种就是隐藏的域偏移。基础模型必须把**接口本身**当成一个随机变量来训练，而不是只把任务当成随机变量。

## 1. 两个词的严谨解读

### 1.1 数据配比：从"采样权重"到"数据投资组合"

**定义（数据域）**：一个数据域 `d = (τ, g, a, s)`，其中 `τ∈[32]` 是任务，`g∈[n_τ]` 是该任务的计分步，`a∈A` 是泛化轴（未见物体/人为撤回/位置/干扰物/背景），`s∈{real, sim, aug, recovery}` 是数据来源。每个域有数据集 `D_d` 与样本数 `N_d`。

**定义（配方）**：配方是单纯形上的权重 `r ∈ Δ^{|D|}`，训练目标为

```text
L(θ; r) = Σ_d r_d · E_{x~D_d}[ ℓ(θ; x) ]
```

`r` 不是"每个任务一个学习率"，而是**一个全局采样分布**——它同时决定模型看到哪些技能、哪些扰动、哪些接口。

**定义（榜单目标）**：对任务 τ，设 `p_{τ,g}(θ)=P(完成第 g 步 | 已到达第 g 步)`，`q_{τ,g}=Π_{j<g} p_{τ,j}` 是到达概率，`w_{τ,g}` 是该步分值（Σ=100）。则

```text
S_τ(θ) = Σ_g w_{τ,g} · q_{τ,g} · p_{τ,g} = Σ_g w_{τ,g} · q_{τ,g+1}
J(θ)   = (1/32) Σ_τ [ q_{τ,n_τ+1} + S_τ(θ)/100 ]
```

（第一项是成功率，第二项是步骤分；与 v2 的计分口径一致。）

**关键推导（数据的分步价值）**：对 `p_{τ,g}` 求偏导，

```text
∂J_τ/∂p_{τ,g} = q_{τ,g} · [ Π_{j>g} p_{τ,j} + (1/100) Σ_{k≥g} w_{τ,k} Π_{g<j≤k} p_{τ,j} ]
             = q_{τ,g} · U_{τ,g}
```

其中 `U_{τ,g}` 是"到达第 g 步后，从第 g 步起还能拿到的期望剩余分（含最终成功率）"。于是

```text
数据价值 V_{τ,g} = q_{τ,g} · U_{τ,g}
```

这不是拍脑袋的加权，而是**榜单目标的精确梯度**：**一步的数据价值 = 到达它的概率 × 它后面还剩多少分**。它自动给出两个反直觉结论：

- 当前所有步都只有 50% 时，**最早的一步价值最高**（它门控后面全部）；
- 当前前置步已经 90%、末步只有 30% 时，**末步价值最高**（前置的 headroom 已经很小）。

**配方公式**：把价值、headroom、轴敏感度、来源可靠性与边际递减放在一起：

```text
r_{τ,g,a,s} ∝ V_{τ,g} · (1 - p_{τ,g}) · A_{g,a} · ρ_s / (1 + N_{τ,g,a,s})^{α}
```

`A_{g,a}` 是"轴 a 的扰动对第 g 步失败率的放大系数"，`ρ_s` 是来源可靠性（真机 > 仿真 > 合成 > 增广），`α` 是缩放律的边际递减指数。这个公式就是本轮的"配方"：**不是按任务平均，而是按"这一步值多少、现在多差、哪条轴最伤它、这类数据多不多"来分配。**

### 1.2 机器人基础模型：从"一个大模型"到"一个可迁移的动作先验"

**定义（本文的 RFM）**：一个语言条件、单套权重的视触觉-动作模型

```text
π_θ: (o_t, l, M) ↦ A_t = (a_t, ..., a_{t+T_a-1})
```

其中 `o_t` 是 4 路 RGB + 本体（关节/末端/夹爪/`lower_body`），`l` 是语言/技能 token，`M` 是评测接口元数据（相机集合、缩放、堆叠帧数、块长、控制空间）。"基础"不指参数量，而指**动作先验的可迁移性**：在任务 A 上学到的"对准—闭合—抬升"能被任务 B 复用。

**为什么它让"配比"有意义**：如果 32 个任务是 32 个独立模型，任务间数据不能互相付红利，配比退化为"每个任务各自采样"；只有在共享骨干下，`D_d` 的梯度才会通过共享表征影响其他任务。**配比是基础模型的遥控器**：它决定共享表征往哪个技能/轴/接口上靠。

**为什么它让"配比"危险**：共享越强，负迁移越强。若把 32 个任务按均匀比例混，视觉上差异大的子数据集会造成**数据集碎片化**，模型学到"哪个数据集/哪种背景 → 哪种动作"的捷径；若某个任务数据太少，它会被其他任务"淹没"。所以配方必须带**每任务下限**与**来源可靠性**，并用留出任务/轴检测负迁移。

### 1.3 耦合：配比是基础模型的控制变量，基础模型是配比的放大器

- 数据少时，**配比 > 规模**：32k episodes 不足以喂饱一个通用大模型，参数再大也主要是过拟合；把同样的数据按价值重排，收益更大。
- 算力少时，**代理 > 全量**：不可能对每个候选配方都训全模型；必须用小组件代理 + 混合律外推。
- 合规严时，**单模型 > 集成**：所有技能头/适配器在导出时合并成一套权重；配比是唯一还能"分而治之"的地方。

## 3. v2 诊断：哪些升级、哪些合并、哪些修剪

- **升级 UIP-14 MSGR → UIP-19 SKT（技能迁移核）**：v2 的技能图只用于推理期路由；本轮把它变成**数据配比的迁移核**——技能重叠度决定"任务 A 的数据对任务 B 值多少"。这是"基础模型"从口号变成可计算权重的关键。
- **升级 UIP-12 DRF → UIP-20 RCP（恢复课程 + 回放）**：v2 的扰动-恢复数据只是"造出来"；本轮把它作为一个**来源域**纳入配方，并加固定回放比例，防止恢复数据淹没干净数据。
- **升级 UIP-13 ACS-2 → UIP-18 HMD（接口随机化 + 视界条件块）**：v2 只调度块长；本轮在**训练期**随机化接口（相机集合/堆叠/缩放/块长），让单模型对评测握手的选择鲁棒。
- **合并 UIP-01′/09′ → 评估探针**：滚动验证与撤回检测不再作为本轮主杠杆，而是作为**估计 `p_{τ,g}` 的在线探针**——配方需要知道"现在哪一步最差"，它们正好提供这个信号。
- **保留** UIP-02′ SSG、UIP-05 LCAG、UIP-08′ LAT-ENG、UIP-11 GSO、UIP-15′ CSG。
- **修剪**：不训 32 个独立模型；不在推理期调用外部 VLM（合规风险）；不假设运行期可换 `T_a`/控制空间；不把仿真权重当成真机权重。
- **新增**：UIP-16 RFM（基础模型底座）、UIP-17 SDR（分数感知数据配方，旗舰）、UIP-18 HMD（接口随机化）、UIP-19 SKT（技能迁移核）、UIP-20 RCP（恢复课程+回放）、UIP-21 PME（代理混合评估）。

## 4. 瓶颈假设

- **H1（最高杠杆）**：按 `V_{τ,g}·(1-p)` 分配数据，比均匀/按任务均衡更能在固定数据预算下提高"成功率+步骤分"；因为榜单目标的梯度本来就是这个形状。
- **H2**：在数据预算固定时，"先买轴覆盖、再买每格条数"优于"每任务均匀加条数"；这与缩放律的多样性结论一致。
- **H3**：技能图加权的跨任务混合优于均匀跨任务混合；但跨任务比例过高会负迁移，存在一个"平衡区间"（与协同训练比例的证据一致）。
- **H4**：训练期接口随机化能显著缩小"训练接口 vs 评测握手接口"的隐藏域偏移，尤其是相机集合与块长。
- **H5**：小代理 + 混合律能在候选配方上给出与全模型**秩相关**足够的预测；若秩相关低，则退回"少数稳健配方 + 真机锚点"，不追求全局最优。

## 5. 候选与合并 → RECIPE

围绕两个词发散 9 个草案（任务级配比、技能级配比、轴级配比、接口随机化、视界混合、代理混合律、恢复课程、负迁移检测、单模型合并），合并为 6 个 UIP，旗舰命名为 **RECIPE**（Robot foundation model with Evaluated Competition-aware data mIxture Protocol）：

- **底座**：UIP-16 RFM。
- **配方**：UIP-17 SDR（价值模型 + 约束 DRO + 混合律）。
- **迁移**：UIP-19 SKT（技能图核）。
- **接口**：UIP-18 HMD（接口随机化 + 边界一致块）。
- **课程**：UIP-20 RCP（恢复数据 + 回放）。
- **评估**：UIP-21 PME（代理混合评估 + 真机锚点）。

旗舰闭环：**用 UIP-01′/09′ 的在线探针估计 `p_{τ,g}` → 用 UIP-17 算价值与配方 → 用 UIP-21 的代理筛选 → 用 UIP-16 训一个模型 → 用 UIP-11 GSO/真机锚点校准 → 回到配方**。

## 6. 本轮最大风险

**一句话**：把"配比"当成可离线精确求解的凸问题，而真实榜单的分布（人扰时机、未见物体、端口元数据）不在代理里，导致代理上最优的配方在真机上反而触发负迁移；必须用**留出任务/轴 + 真机锚点 + 配方稳定性正则**防过拟合。

## 2. 核心数学：Score-Value of Data（SVD）

### 2.1 定义

对任务 τ，计分步 `g=1..n`，分值 `w_g`（Σ=100），步完成概率 `p_g`，到达概率 `q_g=Π_{j<g}p_j`。

```text
S_τ = Σ_g w_g · q_g · p_g
J_τ = q_{n+1} + S_τ/100
```

### 2.2 反向递推（实现用）

令 `R_{n+1}=1`（最终成功项），从 `g=n` 倒推到 1：

```text
V_g = q_g · ( w_g/100 + R_{g+1} )      # 第 g 步的数据价值
R_g = p_g · ( w_g/100 + R_{g+1} )      # 到达 g 后的期望剩余分
```

`V_g` 就是 `∂J_τ/∂p_g` 去掉正因子后的精确形状：**到达概率 × 剩余期望分**。它同时包含"门控价值"（早步）与"末步高分"（晚步），无需手工调"保前置还是搏末步"。

### 2.3 两个算例：同一任务，不同配方

任务 `n=3, w=[30,30,40]`。

| 情形 | `p=[p1,p2,p3]` | `V=[V1,V2,V3]` | headroom `(1-p)` | 归一化配比 | 读法 |
|---|---|---|---|---|---|
| A：全面平庸 | `[0.5,0.5,0.5]` | `[0.80,0.50,0.35]` | `[0.5,0.5,0.5]` | `[0.485,0.303,0.212]` | 最早步门控全部，优先补它 |
| B：前置已好、末步差 | `[0.9,0.6,0.3]` | `[0.732,0.648,0.756]` | `[0.1,0.4,0.7]` | `[0.085,0.301,0.614]` | 末步 headroom 大，优先补它 |

A 情形下，若按"末步分值最高"给末步最多数据，反而会把预算花在 `V` 最小的一步；B 情形下，若按"前置优先"给第一步最多数据，会把预算花在已经 90% 的一步。**SVD 自动在两种策略间切换**——这是本轮最想强调的"配比不是固定规则，而是当前能力的函数"。

### 2.4 配方公式与约束

```text
原始权重  a_d = V_{τ,g} · (1-p_{τ,g}) · A_{g,a} · ρ_s / (1+N_d)^α
配方      r = argmin_{r∈Δ}  -Σ_d r_d·a_d  + β·KL(r || r_prior)  + γ·TV(r, r_prev)
约束      s_τ(r) ≥ floor_τ        （每任务下限，防被淹没）
          s_a(r) ≥ floor_a        （每轴下限，防只刷易轴）
          r_d = 0 if N_d = 0     （没有的数据不能凭空采样）
```

- `β` 是配方稳定性正则（熵/KL），防止权重极端化；
- `γ` 是跨轮稳定性正则，防止每轮重训都换配方导致灾难性遗忘；
- `floor_τ`/`floor_a` 是"安全网"，对应 v2 的步骤分安全网：宁可少赚，不让某任务/某轴归零。

### 2.5 分数约束 Group DRO（SC-DRO）

标准 group DRO 优化最差组，容易把预算全砸在"无望任务"上；榜单要的是平均分。用**约束版**：

```text
max_r  (1/|G|) Σ_{j∈G} s_j(r)
s.t.   s_j(r) ≥ floor_j,  r ∈ Δ

拉格朗日：L = (1/|G|)Σ_j s_j + Σ_j λ_j (s_j - floor_j)
对偶上升：λ_j ← max(0, λ_j + η·(floor_j - s_j))
有效组权重：μ_j = 1/|G| + λ_j
```

这等价于"平均分最大化 + 每任务/每轴不塌方"，比纯 worst-case 更贴合榜单口径。`floor_j` 可以用当前基线或"单任务模型"的分数估计，先设一个保守值（例如基线的 80%），再逐轮抬高。

## 3. 机器人基础模型 RFM：架构与训练目标

### 3.1 架构

```text
图像（最多 4 路，可缺） ──► 视觉编码器（共享） ─┐
语言/技能 token ─────────► 文本编码器（共享） ─┼─► VLM 骨干 ─► action expert ─► 动作块 A_t
本体 q/e/g/lower_body ───► MLP 编码 ───────────┘        │
接口 token M（相机/堆叠/缩放/块长）─────────────────────┘
```

- **单套权重**：视觉/语言/动作专家共享；技能头以 adapter/MoE 形式存在，导出时合并或保留为单模型内部路由，不导出多个独立模型。
- **动作头二选一**：
  - 质量优先：flow matching（π0 路线），适合多峰、精细接触；
  - 延迟优先：并行 L1 回归（OpenVLA-OFT 路线），一次前向出整块，吞吐高；
  - 折中：训练用 flow matching，推理用一致性蒸馏到并行头，**只导出一个头**。
- **动作表示**：统一为 G1+Dex1 的规范向量（左右臂关节、夹爪、`pivot[7]`、必要 base/lower_body 维），非本任务维度置掩码；按维度做稳健归一化（median/IQR）。ReMix 的经验是动作归一化/离散化对混合训练很关键。
- **块长**：模型带 `H` token，预测 `H≤T_a` 步；评测要求固定 `T_a` 时，用"安全保持"补齐尾部（见 3.3）。

### 3.2 接口随机化 HMD（UIP-18）

评测握手时 `M` 固定，但**不同端口/不同场次可能不同**，且训练数据接口与评测接口未必一致。训练时把 `M` 当随机变量：

```text
M = (cameras ⊆ {head_l, head_r, wrist_l, wrist_r},
     stack ∈ {1,2,4},
     resize ∈ {0.5,0.75,1.0},
     jpeg_q ∈ {80,95},
     T_a ∈ {4,8,16},
     control ∈ {joint, ee})
```

- 每个样本/每个 batch 采样一个 `M`；缺失相机用可学习的 missing token；
- 至少保留 1 个头部 + 1 个腕部，避免"全丢"退化成盲策略；
- 对图像做缩放/JPEG 近似退化，匹配 `web_policy.py` 的 q95 4:4:4 传输；
- 语言做同义改写/模板混合，避免记住固定句式。

这不是"数据增广"的普通技巧，而是**把接口当成域随机化**：让一个模型在评测端无论选哪种相机/堆叠/块长都不崩。

### 3.3 边界一致块 BCC（并入 UIP-18）

评测端整块执行后才重观测，块切换处最容易出现动作跳变。训练时随机采样块边界 `b`：

```text
输入：o_t, 已执行的动作前缀 a_{t-b:t}, 视界 token H
输出：a_{t:t+H}
损失：L_action + λ_bc · ||π(o_t, a_{t-b:t}) - a_{t:t+H}||²
```

推理时把上一块实际执行的动作作为前缀条件，减少"新块不认旧块"的跳变。若 `T_a` 固定而模型只想执行 `H<T_a`，尾部用"保持/回撤"安全动作补齐——这与 v2 的"块尾安全形态"一致。

### 3.4 训练目标

```text
L(θ) = E_{M~p(M)} E_{(o,a)~D(r)} [ L_action(π_θ(o,l,M), a) ]
       + λ_aux·L_skill + λ_bc·L_boundary
       + λ_reg·||θ - θ_prev||²          # 防灾难性遗忘（可选）
```

`L_skill` 是技能/子目标辅助头（与 UIP-14 技能图对齐），只训练时用，导出可丢；`L_reg` 在加入恢复数据时开启。

## 4. 技能迁移核 SKT（UIP-19）

### 4.1 技能图

把 32 个任务映射到约 10 个技能节点（抓取、放置、插入、倒出、拉链、折叠、堆叠、按色分拣、开合、挑取），边表示计分步顺序。每个任务 τ 有一个技能分布 `h_τ ∈ Δ^{10}`（由计分点文本 + 演示动作聚类得到）。

### 4.2 迁移权重

```text
Q_{τ,d} = sim(h_τ, h_{τ(d)}) · ρ_{s(d)} · sim_action(τ, τ(d))
```

- `sim(h_τ, h_τ')`：技能分布的余弦/JS 相似度；
- `sim_action`：动作空间重叠（同一 embodiment 下主要是任务用到的维度/频率）；
- `ρ_s`：来源可靠性（真机 1.0、仿真 0.7、合成 0.5、增广 0.3，可校准）。

**配比中的跨任务项**：

```text
r_cross(τ←τ') ∝ Q_{τ,τ'} / (1 + N_{τ'})^{α} · (1 - overlap_penalty)
```

`overlap_penalty` 惩罚"任务 τ 已经很多、τ' 只是重复"的情况。均匀跨任务混合相当于 `Q≡1`，是本方案的消融对照。

### 4.3 防负迁移

- 每个任务保留一个"单任务基线"分数 `s_τ^{single}`（小模型即可）；
- 训练后若 `s_τ < s_τ^{single} - δ`，判定负迁移，降低该任务对其他任务的数据权重，或提高其自身数据下限；
- 用留出任务（held-out task）做"零样本迁移"测试：在 32 任务中留 2–3 个完全不参与配方优化，只用于检验迁移核是否真的泛化。

## 5. 恢复课程与回放 RCP（UIP-20）

v2 的 DRF 生成 `(完成 → 撤回 → 恢复)` 数据。本轮把它作为**来源域**纳入配方：

```text
r_recovery(τ,g) ∝ V_{τ,g} · (1-p^{clean}_{τ,g}) · 1[g 有撤回型干扰]
```

- 只对 `human_*` 明确为撤回型的步生成/采样恢复数据（v2 §2 表中 ★ 的 11+ 个任务）；
- 恢复数据与干净数据**固定回放比** `r_clean : r_recovery = 4:1`（可扫），防止恢复数据淹没干净行为；
- 课程顺序：干净 → 轴增广 → 撤回 → 恢复；但**最终配方**仍按 SVD 权重，不按课程顺序（课程只影响训练轨迹，不改变最终分布）；
- 若恢复数据来自仿真，`ρ_sim` 降低，并在真机锚点上校准其价值。

## 6. 代理混合评估 PME（UIP-21）

### 6.1 为什么需要代理

32 任务 × 5 轴 × 若干技能/来源 = 上百个域；对每个候选配方训全模型不可行。用**小代理 + 混合律**：

```text
s_τ(r) ≈ s_τ^∞ - A_τ · [ Σ_d r_d · N_d · Q_{τ,d} ]^{-α_τ}
```

- `s_τ^∞`：该任务的数据上限（可用大模型/人类上限估计）；
- `A_τ, α_τ`：从代理实验拟合的缩放参数；
- `Q_{τ,d}`：技能迁移核给出的有效数据倍率；
- 这个式子把"自己的数据"和"别人的数据"统一成"有效样本量"，比纯经验网格更可外推。

### 6.2 代理实验设计

1. 训练一个小代理（宽度/层数约为全模型 1/4–1/10），固定 token/step 预算；
2. 用 Dirichlet 采样 + 单纯形顶点 + 均匀/任务均衡等基线，构造 10–16 个候选配方；
3. 每个配方在**留出 episode** 上评估成功率/步骤分（或 GSO 结构分）；
4. 拟合上式；用留出的 3–4 个配方检验**秩相关**（Spearman ρ）；
5. 在约束下优化 `r`，取 top-3；全模型训 top-1，top-2/3 作回退；
6. 真机锚点：用少量真机/仿真 rollout 校准 `ρ_s` 与 `s_τ^∞`。

### 6.3 判定门槛

- 若代理-真机秩相关 `ρ < 0.5`：**不做全局配方优化**，只保留"均匀/任务均衡/SVD"三个稳健配方做小规模对照；
- 若 `ρ ≥ 0.5`：允许用混合律外推，但仍保留真机锚点；
- 若配方在 3 个随机种子上的权重排序不稳定（Kendall τ < 0.6）：加 `β`/`γ` 正则，或直接取平均配方。

## 9. 合规、审计与风险

### 9.1 合规红线

- **单模型**：推理时只加载一套权重；adapter/MoE 合并或内部路由，不导出多模型集成；不调用外部 VLM/API 做推理。
- **数据来源**：公开 32 数据集的使用条款需核对；合成/仿真数据是否允许需书面确认；人体数据不采集。
- **接口**：动作形状/dtype/token/块长严格按 README；不运行期切 joint/ee；返回块长与声明一致。
- **可信度**：不靠"异常规律的动作"刷分；延迟/抖动纳入 UIP-15′ 预算。

### 9.2 必须先做的审计

- **A0（代理可信）**：代理排名与真机/榜单排名的秩相关；`ρ<0.5` 则配方优化降级为三配方对照。
- **A1（单模型）**：书面确认"单模型"的确切定义；若允许多模型，仍优先单模型（延迟/并发）。
- **A2（合成数据）**：仿真/合成/增广数据是否计入训练、是否允许；不允许则只用公开数据 + 图像增广。
- **A3（人扰可观测）**：评测是否真有人、干扰是否脚本化；决定恢复数据是"主域"还是"条件域"。
- **A4（端口元数据）**：N 个端口是否可能用不同 `M`；决定 HMD 的随机化范围。
- **A5（数据条款）**：32 个 HF 数据集的 license/再分发限制。

### 9.3 风险

- **代理过拟合**：在 32 个任务上调配方，容易把"留出任务"也间接拟合进去；必须留 2–3 个任务完全不参与优化。
- **负迁移**：跨任务比例过高会伤害单任务；用 floor + 单任务基线 + E210 监控。
- **仿真域偏移**：`ρ_sim` 不是常数，接触密集步会低估；用真机锚点分段校准。
- **配方不稳定**：小数据上 SVD 权重方差大；用 `β`/`γ` 正则 + 多种子平均。
- **合规误判**：把"技能头"当成多模型；导出前做权重合并与接口审计。

---

## 10. 资源与时间线（粗排）

- **第 1–2 周**：数据审计（32 数据集、动作空间、技能标签、轴标签）；统一动作表示；跑通单任务基线。
- **第 3–4 周**：RFM 骨架（VLM 骨干 + action expert + 视界 token）；HMD/BCC 接入；搭代理评估管线。
- **第 5–6 周**：SVD 价值模型 + SC-DRO；10–16 个候选配方的代理实验；拟合混合律。
- **第 7–8 周**：全模型训练 top-3 配方；SKT 迁移核；RCP 恢复数据与回放。
- **第 9 周起**：真机/榜单锚点；校准 `ρ_s`/`s_τ^∞`；迭代配方；做 E209/E210 守门。

---

## 11. 本轮最大风险 & 押注

**一句话**：若代理排名与真机排名不相关，SVD 配比就是在"优化一个假的榜单"，越优化越偏；因此 E209 必须先于大规模训练，且任何配方都要保留"均匀/任务均衡"两个回退。

**→ 押注：UIP-17 SDR（分数感知配方）× UIP-16 RFM（单模型底座）× UIP-19 SKT（技能迁移核）**——它把"单模型多任务"的合规约束从限制变成杠杆：同一个骨干下，数据配比是唯一能同时改善 32 个任务、又不违反单模型规则的自由度；而 SVD 给出了这个自由度的精确梯度形状。
