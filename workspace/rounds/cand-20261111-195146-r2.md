# 第 56 轮（承接第 55 轮；灵感循环第 2 轮；本轮灵感：「用户需求分析」×「关节驱动」）

> 第 55 轮把证书从“动作覆盖”下探到“语义-接触是否可信、全身耦合是否可行”。本轮继续往下探两层此前被默认当成“给定”的东西：**任务为什么值得做（用户需求）** 与 **动作凭什么被执行（关节驱动）**。核心矛盾：**H24**：第 53–55 轮的证书都在“任务已给定、风险已给定”的前提下证明安全，但任务的价值、安全阈值与优先级其实来自用户需求，需求是分布式的、会漂移的、且彼此冲突——把安全证书当绝对真理，就会对高价值低风险需求过度保守、对低价值高风险需求过度冒险；**H25**：第 54 轮的动作剖面 `α_S` 与第 55 轮的生存核 `K(Σ)` 都把执行器能力当作静态约束，但真实关节驱动是**带热记忆、被母线功率耦合、会磨损退化的可耗尽资源**，一条 t=0 时“可行”的轨迹会在任务中段因降额而让证书**静默过期**。

## 0. 直觉与动机

**灵感 1（用户需求分析 → 需求不是任务串，而是“偏序 + 风险容忍 + 验收算子”）**
直觉：用户说“帮我搬箱子”，真正给出的不是一个动作序列，而是一组带优先级的需要：不能摔（must）、尽量快（should）、别太吵（could），并且“多快值得冒多大风险”取决于上下文。把它写成硬编码任务，等于替用户擅自做了价值判断。更合理的表示是 **需求剖面** `R = (N, ≼, u, κ_risk, A_R)`：需要项集合、优先级偏序、效用、风险容忍、以及把“证书 + 计划”映射为 `{接受, 降级, 拒绝}` 的 **验收算子**。这借鉴需求工程里的 MoSCoW（Must/Should/Could）与 Kano 分层，但关键差别是：**验收算子的输入必须是可验证的证书，而不是“看起来能做到”**。

**灵感 2（关节驱动 → 能力包络是状态，不是常数）**
直觉：关节驱动不是一个 `τ_max` 数字。给定电机（`K_t, K_e, R`）、减速器（额定/峰值力矩、背隙、润滑温度）与母线电压，实际可行的 `(τ,ω)` 集随温度、累计负载、磨损与母线功率而收缩：绕组温升 `C dT/dt = I²R - h(T-T_amb)`，磁钢高温退磁让 `K_t` 永久下降，多关节同时大电流又通过 **共享母线功率** `Σ τ_j ω_j ≤ P_bus` 相互挤压。于是驱动包络写成 `E(e)`，其中 `e` 是驱动状态（温度、母线电压、磨损、累计力矩）。**执行能力是一笔会被花掉、也会自己恢复的预算。**

**灵感 3（需求 × 驱动 → 热-功率预算分配，而非平均用力）**
直觉：不同需求对驱动的“花法”不同。“平稳端水”要低力矩高带宽，“快速蹲起”要高峰值力矩，“长时间巡检”要低热耗。用户优先级 `≼` 应当决定把有限的热/功率预算优先分给哪些关节、哪些任务阶段；全身冗余（用腿分担、髋膝分工、臂腿协同）则提供了在同一份预算下重新分配的自由度。这把第 54–55 轮的“动作可行性”升级为 **“在给定需求与驱动预算下的可兑现性”**。

**灵感 4（需求-驱动证书 → 从“安全”到“值得且兑现得了”）**
直觉：第 55 轮的 `J_s` 只回答“在语义扰动内动作是否安全”。新证书必须再回答两件事：这份安全是否服务于用户真正要的东西（`R_core, δ_r`），以及它能否在驱动包络内被兑现而不透支未来（`E_core, T_margin, D, ρ_req`）。**可部署 = 需求被正确理解 ∧ 安全被证明 ∧ 驱动兑现得了 ∧ 余量足以覆盖漂移。**

**灵感 5（在线需求协商 → 用“分级降级”代替“安全制动”一刀切）**
直觉：第 55 轮的兜底是 `u_stop`（制动）。但驱动不够时，用户往往更愿意“慢一点 / 分两次搬 / 换只手”，而不是原地停机。因此当 `R` 在 `E` 下不可兑现时，应沿一个 **降级格** 协商：放松目标、放宽时限、降低性能换安全、切换冗余策略，实在不行才请求用户或停机。协商必须保证 **每一步降级风险不增、效用损失有界、过程有限终止**——需求分析由此从离线规格变成在线闭环。

## 1. 形式化定义（增量：定义 127–132）

**定义 127（需求剖面与验收算子）**
需求剖面 `R = (N, ≼, u, κ_risk, C_ctx, A_R)`：
- `N = {n_i}` 需要项，`n_i = (g_i, w_i, c_i)`（目标、权重、约束类型 ∈ {must, should, could}）；
- `≼` 为优先级偏序，`u: 计划 → ℝ` 为效用，`κ_risk: C_ctx → [0,1]` 为上下文相关风险容忍；
- 验收算子 `A_R(J, π) ∈ {accept, degrade, reject}`，`J` 为证书、`π` 为计划。
需求可兑现率 `η_R(π) = Σ_i w_i·1[n_i 被满足] / Σ_i w_i`；must 项未满足直接 `reject`。

**定义 128（关节驱动状态与耦合能力包络）**
关节 `j` 的驱动状态 `e_j = (T_j^w, V_bus, w_j, m_j)`（绕组温度、母线电压、磨损、累计力矩）。能力包络
`E_j(e_j) = {(τ,ω) | |τ| ≤ τ_max^j(T_j^w,w_j), ω ∈ [ω_min,ω_max(V_bus)], τ·ω ≤ P_j^cont, τ/ω 满足减速器许用}`。
全身包络不是各关节笛卡尔积，而是被共享母线约束收紧：
`E(e) = { (τ,ω) ∈ ∏_j E_j(e_j) | Σ_j (τ_jω_j + loss_j) ≤ P_bus(V_bus) }`。
热动力学（慢时间尺度）：
`C_j dT_j^w/dt = I_j²R_j + c_f|τ_jω_j| - h_j(T_j^w - T_amb)`，`I_j = τ_j/K_t^j(T_j^w,w_j)`。

**定义 129（需求-驱动可兑现性与增广生存核）**
令增广状态 `z=(x,e)`，接触可供性沿用第 55 轮 `C^+(Σ)`。称 `z` 在需求 `R` 下可兑现，若存在计划 `π` 与输入 `u`：
`ẋ=f(x,u,λ), ė=g_th(e,τ,ω), supp(λ)⊆C^+(Σ), (τ,ω)∈E(e), 且 A_R(J,π)≠reject`。
增广生存核 `K_R(Σ,e) = {x | ∃π,u : 上式成立且 x 在时限内到达 g_i}`。
**引理 1（能力单调性）**：若 `e'` 相对 `e` 温度更低、母线更足、磨损更小（能力占优），则 `K_R(Σ,e') ⊇ K_R(Σ,e)`。故 `K_R(Σ,e) ⊆ K(Σ)`，驱动约束是第 55 轮生存核的**收紧**而非替代。

**定义 130（驱动预算与能力债）**
预算 `B = (B_j^th, B^power)`；分配 `a_j(t) ≥ 0, Σ_j a_j ≤ B`。**能力债**
`D_j(t) = τ_max^j(T_amb,0) - τ_max^j(T_j^w(t), w_j(t))`，即已透支掉的可用力矩。
要求沿轨迹 `D_j(t) ≤ D_max` 且 `T_j^w(t) ≤ T_j^safe`；预算分配的目标是在满足安全与 `D_max` 下最大化 `η_R`。

**定义 131（需求-驱动联合证书）**
`J_r = (R_core, C_core, E_core, B_alloc, T_margin, ρ_req, δ_r, D, evidence)`：
- `R_core` 本轮实际服务的需要项子集及验收结果；
- `C_core` 沿用第 55 轮核心接触集；
- `E_core` 标定后的驱动包络及其保守内/外近似；
- `B_alloc` 预算分配、`T_margin = min_t min_j (T_j^safe - T_j^w(t))`；
- `ρ_req` 在需求漂移与驱动退化联合扰动下仍需兑现的概率下界；
- `δ_r = d(R, R̂)` 需求理解误差，`D = max_j D_j(t)`。
**可部署** 当且仅当：`R_core` 校准通过（`δ_r<Θ_r`）、must 项全满足、`E_in ⊆ E ≤ E_out`、`T_margin ≥ θ_T`、`D ≤ D_max`、`ρ_req ≥ ρ_min`。

**定义 132（需求协商算子与降级格）**
降级格 `(ℛ, ⪯)`：`R' ⪯ R` 表示放松（降低目标、延长时限、以性能换安全、切换冗余策略）。协商算子 `N(R, evidence) → R' ⪯ R`，满足：
(i) **风险不增**：`risk(R') ≤ risk(R)`；
(ii) **效用有界损失**：`u(R) - u(R') ≤ ε_u`；
(iii) **有限终止**：`ℛ` 上无无限严格下降链，每轮至少移除一个 must→should 冲突。
只有当 `N` 也无法给出可兑现 `R'` 时，才回退第 55 轮的安全制动或请求用户。

## 2. 关键算法 伪代码

### IP-127 NPA（Need Profile Analysis）

```python
def analyze_need(utterance, history, context):
    N = extract_need_items(utterance, history)         # MoSCoW/Kano 分层
    preorder = elicit_priority(N)                       # 交互 + 历史偏好
    kappa = risk_tolerance(context, history)            # 上下文相关
    def A_R(cert, plan):
        if any(n.type == 'must' and not n.satisfied(plan) for n in N):
            return 'reject', 'must_violated'
        eta = weighted_realization(N, plan)
        if eta >= 1.0 and cert.T_margin >= theta_T:
            return 'accept', eta
        return 'degrade', eta
    return NeedProfile(N, preorder, kappa, A_R)
```

### IP-128 DCE（Drive Capability Envelope）

```python
def drive_envelope(joint, e, horizon, P_bus):
    # 用电流/温度/母线观测估计 e，并向前预测热-功率包络
    E = []
    for k in range(horizon):
        tau_max = tau_max_of(joint, e.T_w, e.wear) * derate(e.T_w)
        w_max = w_max_of(e.V_bus, tau_max, joint)
        E.append(Box(tau=tau_max, omega=(joint.w_min, w_max),
                     P=joint.P_cont))
        e = thermal_step(e, joint, load=tau_max*joint.w_max)  # 最坏加热预测
    E_coupled = add_bus_constraint(E, P_bus)                # Σ τω ≤ P_bus
    return Envelope(in=E_coupled.shrink(eps_in),
                    out=E_coupled.grow(eps_out), e_next=e)
```

### IP-129 RBA（Requirement-Budget Allocator）

```python
def allocate_budget(R, E, D_prev, horizon):
    # 按需要项优先级，把热/功率预算分给关节与阶段；优先级高者先满足
    items = sorted(R.N, key=R.rank)                        # must 优先
    a = init_allocation(items, E)
    for n in items:
        if n.type == 'must':
            a = solve_min_budget(n, a, E, hard=True)       # 硬约束
        else:
            a = solve_tradeoff(n, a, E, u=R.u, D_max=D_max,
                               w=n.w)                      # 软目标
    if not feasible(a, E) or exceeds(a, D_prev):
        return None, diagnose_infeasible(a, E, D_prev)
    return a, 'ok'
```

### IP-130 NAC（Need-Actuation Certificate）

```python
def need_actuation_certificate(plan, R, Sigma, E, budgets):
    R_core = needs_served(plan, R)
    if any(n.type == 'must' and not n.satisfied(plan) for n in R_core):
        return ('reject', 'must_unmet')
    C_core = conservative_contacts(Sigma, budgets.theta_m)  # 第 55 轮
    if not C_core:
        return ('reject', 'no_core_contact')
    T_margin = min(budgets.T_safe - T_w(t) for t in plan.trajectory)
    D = max(capability_debt(t) for t in plan.trajectory)
    delta_r = need_drift(R_core, R_hat)
    rho_req = worst_case_realization(R, E, Sigma, eps_r=delta_r)
    if T_margin < budgets.theta_T or D > budgets.D_max:
        return ('reject', 'actuation_budget_exceeded', T_margin, D)
    if delta_r > budgets.Theta_r:
        return ('reject', 'need_drift_exceeded', delta_r)
    if rho_req < budgets.rho_min:
        return ('reject', 'requirement_robustness_fail', rho_req)
    return ('ok', NeedActuationCert(R_core, C_core, E, T_margin, rho_req, delta_r, D))
```

### IP-131 NNP（Need Negotiation Protocol）

```python
def negotiate(R, evidence, lattice, budget_eps_u):
    frontier = [R]
    spent = 0.0
    while frontier:
        R_cur = pop_highest_utility(frontier)
        if realizable(R_cur, evidence):
            return ('ok', R_cur)
        for R_next in lattice.successors(R_cur):          # 放松一级
            loss = R.utility() - R_next.utility()
            if loss <= budget_eps_u - spent and risk_non_increasing(R_cur, R_next):
                frontier.append(R_next)
        spent += 1e-3                                     # 记账，防无限降级
    return ('request_user_or_stop', best_effort(R))
```

### IP-132 DVE（Drive-Aware Viability Extension）

```python
def drive_viability_kernel(Sigma, E, x0, e0, horizon, eps):
    # 慢热状态 + 快动力学的双时间尺度：外层枚举热轨迹，内层复用第 55 轮核
    K_in, K_out = set(), set()
    for e_traj in sample_thermal_trajectories(e0, horizon, eps):
        for k, e in enumerate(e_traj):
            K_k = viability_kernel(Sigma | contacts(E), x0, horizon-k)  # 第 55 轮
            K_in |= K_k.K_in if envelope_is_inner(e) else set()
            K_out |= K_k.K_out
    return KernelApprox(K_in=K_in, K_out=K_out, margin=min_thermal_margin(e_traj))
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| NPA | O(\|N\|·\|历史\| + 交互轮数) | O(\|N\|) | 偏好一致性、验收算子单调 |
| DCE | O(H·\|J\|) | O(H·\|J\|) | 热-功率预测偏差有界、包络外近似 sound |
| RBA | O(\|N\|·QP) | O(\|J\|·H) | 预算闭合、must 项可行优先 |
| NAC | O(\|轨迹\|·\|J\| + N_adv) | O(\|轨迹\|·\|J\|) | δ_r 预算闭合、ρ_req 下界有效 |
| NNP | O(\|ℛ\|·\|successors\|) | O(\|ℛ\|) | 降级风险不增、有限终止 |
| DVE | O(N_th·H·\|X\|·QP) | O(\|X\|·H) | 双时间尺度误差可控、核保守包含 |

**正确性定理（Need-Actuation Realization Soundness）**
假设第 55 轮 (A29)–(A32) 成立；并新增：
**(A33)** 验收算子 `A_R` 在偏好扰动下单调，需求漂移 `δ_r ≤ Θ_r` 且校准通过；
**(A34)** 驱动包络外近似 sound：`E_in ⊆ E_true ⊆ E_out`，热预测误差 `≤ ε_th`；
**(A35)** 预算分配满足 `Σ_j a_j ≤ B`、`T_j^w ≤ T_j^safe`、`D_j ≤ D_max`；
**(A36)** 协商算子满足定义 132 的 (i)–(iii)。
则部署后“安全地兑现用户需求”的概率：
```
P(realize) ≥ 1 - P(δ_r > Θ_r) - P(E_out \ E_in ≠ ∅) - P(|T̂_w - T_w| > ε_th)
              - P(D > D_max) - P(NNP 未终止) - (1 - ρ_sem) - P(shield fallback fails)
```
关键：**需求进验收、驱动状态进生存核、预算显式分配、降级有格可依**。任一层失守，都不允许把“证书通过”当成“用户满意且驱动撑得住”。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 需求误读 / 需求漂移 | 高 | 在线澄清 + must 项强制确认 + `δ_r` 触发重验收 |
| 热模型偏差导致包络非 sound | 高 | 包络外近似 + 温度传感器在线校正 + 保守降额 |
| 母线功率耦合被忽略 | 高 | 共享母线约束进 `E(e)` + 峰值功率限幅 |
| 预算分配饥饿（某些关节长期过热） | 中 | 公平性约束 + 关节轮换 + `D_max` 硬上限 |
| 协商陷入无限降级或效用崩塌 | 中 | 降级格有限 + 效用损失预算 + 超时请求用户 |
| 需求分析与安全证书口径不一致 | 高 | 统一以证书为验收输入，禁止“语言承诺”绕过证书 |

## 6. 本轮最大风险

**一句话**：需求-驱动接地把证书从“动作是否安全”推进到“需求是否值得且驱动是否兑现得了”，但其 soundness **双重依赖主观需求的可校准性与物理驱动模型的可信度**；一旦需求被误读（把 could 当 must、或漏掉真正的 must）、或热-母线模型系统性偏乐观，系统会在**自洽但错误**的 `R_core` 与 `E_core` 上签发“可兑现”证书，于任务中段遭遇静默降额，既没做对用户要的事、又让全身控制器在真实包络之外发力——因此必须以 **must 项强制确认 + 包络保守外近似 + 热裕度硬约束 + 效用有界协商** 四重护栏，宁可分级降级或请求用户，绝不把“需求听起来合理”与“驱动此刻够用”当作“任务一定能兑现”。

# 第 56 轮产物 · 创新点清单 v32：GroundEdge-NeedDrive++（NPA×DCE×RBA×NAC×NNP×DVE）

> 承接第 54 轮产物 v31（ACS×SCOM×CEC×AEC×JTC），并正式纳入第 55 轮的 **语义-接触层**（IP-121–IP-126），本轮再叠加 **需求-驱动层**：
> - **NPA（Need Profile Analysis）**：把用户需求表示为偏序 + 风险容忍 + 验收算子 `R`；
> - **DCE（Drive Capability Envelope）**：把关节驱动能力写成含热记忆、母线耦合、磨损的状态化包络 `E(e)`；
> - **RBA（Requirement-Budget Allocator）**：按需求优先级分配热/功率预算；
> - **NAC（Need-Actuation Certificate）**：需求-驱动联合证书 `J_r`；
> - **NNP（Need Negotiation Protocol）**：沿降级格做风险不增的分级协商；
> - **DVE（Drive-Aware Viability Extension）**：用双时间尺度把驱动状态并入第 55 轮生存核。
>
> IP 编号：IP-127~IP-132（共 6 个新增）；继承 IP-121~IP-126。版本记为 **v32 = v31 + v31.5(语义-接触) + v32(需求-驱动)**。

## 1. 符号体系增量（定义 127–132）

| 符号 | 含义 |
|---|---|
| `R=(N,≼,u,κ_risk,C_ctx,A_R)` | 需求剖面；`N` 需要项，`≼` 优先级，`A_R` 验收算子 |
| `η_R(π)` | 需求可兑现率（加权 + must 硬约束） |
| `e_j=(T_j^w,V_bus,w_j,m_j)` | 关节驱动状态（温度、母线、磨损、累计力矩） |
| `E_j(e_j), E(e)` | 单关节包络；受 `Σ τ_jω_j ≤ P_bus` 收紧的全身耦合包络 |
| `K_R(Σ,e)` | 需求-驱动增广生存核，`K_R ⊆ K(Σ)` |
| `B=(B^th,B^power), a_j` | 驱动预算与分配 |
| `D_j(t)` | 能力债：已透支的可用力矩 |
| `J_r` | 需求-驱动联合证书 |
| `(ℛ,⪯), N` | 降级格与需求协商算子 |
| `ρ_req` | 需求漂移 + 驱动退化联合扰动下的兑现概率下界 |

**定义 127（需求剖面与验收算子）**
`R=(N,≼,u,κ_risk,C_ctx,A_R)`，`n_i=(g_i,w_i,c_i)`，`c_i∈{must,should,could}`；`A_R(J,π)∈{accept,degrade,reject}`，must 项未满足直接 reject。
**定义 128（驱动包络）**
`E(e)={(τ,ω)∈∏_j E_j(e_j) | Σ_j(τ_jω_j+loss_j) ≤ P_bus}`；`C_j dT_j^w/dt = I_j²R_j + c_f|τ_jω_j| - h_j(T_j^w-T_amb)`。
**定义 129（增广生存核）**
`K_R(Σ,e)={x | ∃π,u: ẋ=f, ė=g_th, supp λ⊆C^+(Σ), (τ,ω)∈E(e), A_R(J,π)≠reject}`；能力单调性给出 `K_R(Σ,e)⊆K(Σ)`。
**定义 130（预算与能力债）**
`D_j(t)=τ_max^j(T_amb,0)-τ_max^j(T_j^w(t),w_j(t)) ≤ D_max`。
**定义 131（联合证书）**
`J_r=(R_core,C_core,E_core,B_alloc,T_margin,ρ_req,δ_r,D,evidence)`；可部署需 `δ_r<Θ_r`、must 全满足、`E_in⊆E⊆E_out`、`T_margin≥θ_T`、`D≤D_max`、`ρ_req≥ρ_min`。
**定义 132（协商算子）**
`N(R,evidence)=R'⪯R`，满足风险不增、效用损失 `≤ε_u`、有限终止；否则请求用户或安全制动。

## 2. 关键算法 伪代码

### IP-127 NPA

```python
def analyze_need(utterance, history, context):
    N = extract_need_items(utterance, history)        # MoSCoW/Kano
    preorder = elicit_priority(N)
    kappa = risk_tolerance(context, history)
    def A_R(cert, plan):
        if any(n.type == 'must' and not n.satisfied(plan) for n in N):
            return 'reject', 'must_violated'
        eta = weighted_realization(N, plan)
        if eta >= 1.0 and cert.T_margin >= theta_T:
            return 'accept', eta
        return 'degrade', eta
    return NeedProfile(N, preorder, kappa, A_R)
```

### IP-128 DCE

```python
def drive_envelope(joint, e, horizon, P_bus):
    E = []
    for k in range(horizon):
        tau_max = tau_max_of(joint, e.T_w, e.wear) * derate(e.T_w)
        w_max = w_max_of(e.V_bus, tau_max, joint)
        E.append(Box(tau=tau_max, omega=(joint.w_min, w_max), P=joint.P_cont))
        e = thermal_step(e, joint, load=tau_max * joint.w_max)   # 最坏加热预测
    E_coupled = add_bus_constraint(E, P_bus)                     # Σ τω ≤ P_bus
    return Envelope(in=E_coupled.shrink(eps_in),
                    out=E_coupled.grow(eps_out), e_next=e)
```

### IP-129 RBA

```python
def allocate_budget(R, E, D_prev, horizon):
    items = sorted(R.N, key=R.rank)                  # must 优先
    a = init_allocation(items, E)
    for n in items:
        if n.type == 'must':
            a = solve_min_budget(n, a, E, hard=True)
        else:
            a = solve_tradeoff(n, a, E, u=R.u, D_max=D_max, w=n.w)
    if not feasible(a, E) or exceeds(a, D_prev):
        return None, diagnose_infeasible(a, E, D_prev)
    return a, 'ok'
```

### IP-130 NAC

```python
def need_actuation_certificate(plan, R, Sigma, E, budgets):
    R_core = needs_served(plan, R)
    if any(n.type == 'must' and not n.satisfied(plan) for n in R_core):
        return ('reject', 'must_unmet')
    C_core = conservative_contacts(Sigma, budgets.theta_m)   # IP-121/123
    if not C_core:
        return ('reject', 'no_core_contact')
    T_margin = min(budgets.T_safe - T_w(t) for t in plan.trajectory)
    D = max(capability_debt(t) for t in plan.trajectory)
    delta_r = need_drift(R_core, R_hat)
    rho_req = worst_case_realization(R, E, Sigma, eps_r=delta_r)
    if T_margin < budgets.theta_T or D > budgets.D_max:
        return ('reject', 'actuation_budget_exceeded', T_margin, D)
    if delta_r > budgets.Theta_r:
        return ('reject', 'need_drift_exceeded', delta_r)
    if rho_req < budgets.rho_min:
        return ('reject', 'requirement_robustness_fail', rho_req)
    return ('ok', NeedActuationCert(R_core, C_core, E, T_margin, rho_req, delta_r, D))
```

### IP-131 NNP

```python
def negotiate(R, evidence, lattice, budget_eps_u):
    frontier, spent = [R], 0.0
    while frontier:
        R_cur = pop_highest_utility(frontier)
        if realizable(R_cur, evidence):
            return ('ok', R_cur)
        for R_next in lattice.successors(R_cur):
            loss = R.utility() - R_next.utility()
            if loss <= budget_eps_u - spent and risk_non_increasing(R_cur, R_next):
                frontier.append(R_next)
        spent += 1e-3
    return ('request_user_or_stop', best_effort(R))
```

### IP-132 DVE

```python
def drive_viability_kernel(Sigma, E, x0, e0, horizon, eps):
    K_in, K_out = set(), set()
    for e_traj in sample_thermal_trajectories(e0, horizon, eps):
        for k, e in enumerate(e_traj):
            K_k = viability_kernel(Sigma | contacts(E), x0, horizon - k)  # IP-122
            K_in |= K_k.K_in if envelope_is_inner(e) else set()
            K_out |= K_k.K_out
    return KernelApprox(K_in=K_in, K_out=K_out, margin=min_thermal_margin(e_traj))
```

## 3. 与 v31 / v31.5 的接口

- **对 ACS/SCOM**：动作剖面 `α_S` 增加“驱动状态”条件，`α_S(a|e)`；组合边要求两技能在共享预算下可拼接，`compat_e(S_i,S_j|B)`。
- **对 WBV/SSF**：`K_R(Σ,e) ⊆ K(Σ)`，护盾约束从 `x∈K_in(Σ)` 升级为 `x∈K_in(Σ,e)`；驱动不可兑现时先走 NNP，再回退 `u_stop`。
- **对 J_s/AEC**：`J_r` 是 `J_s` 的超集（多出 `R_core,E_core,B_alloc,T_margin,ρ_req,δ_r,D`），联合证书升级为 `J∪J_s→J_r`。
- **对 CEC**：云端用 `R` 做粗需求分解，边端用 `E(e)` 做驱动可行校验；边端回传的不再只是语义边界，还有驱动降额与预算冲突。

## 5. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| NPA | O(\|N\|·\|历史\|+交互) | O(\|N\|) | 偏好一致、验收单调 |
| DCE | O(H·\|J\|) | O(H·\|J\|) | 热-功率预测有界、外近似 sound |
| RBA | O(\|N\|·QP) | O(\|J\|·H) | 预算闭合、must 优先可行 |
| NAC | O(\|轨迹\|·\|J\|+N_adv) | O(\|轨迹\|·\|J\|) | δ_r 预算闭合、ρ_req 下界有效 |
| NNP | O(\|ℛ\|·successors) | O(\|ℛ\|) | 风险不增、有限终止 |
| DVE | O(N_th·H·\|X\|·QP) | O(\|X\|·H) | 双时间尺度误差可控、核保守包含 |

**正确性定理（Need-Actuation Realization Soundness）**
假设 v31.5 (A29)–(A32) 成立；并新增 **(A33)** `A_R` 在偏好扰动下单调且 `δ_r≤Θ_r`；**(A34)** `E_in⊆E_true⊆E_out` 且热预测误差 `≤ε_th`；**(A35)** `Σ_j a_j≤B`、`T_j^w≤T_j^safe`、`D_j≤D_max`；**(A36)** 协商算子满足定义 132 的 (i)–(iii)。
则：
```
P(realize) ≥ 1 - P(δ_r>Θ_r) - P(E_out\E_in≠∅) - P(|T̂_w-T_w|>ε_th)
              - P(D>D_max) - P(NNP 未终止) - (1-ρ_sem) - P(shield fallback fails)
```
关键：**需求进验收、驱动进核、预算显式、降级有格**；四层任一失守，都不能把“证书通过”当成“用户满意且驱动撑得住”。

## 6. 本轮最大风险

**一句话**：需求-驱动接地把证书从“动作安全”推进到“需求值得且驱动兑现得了”，但其 soundness **双重依赖主观需求的可校准性与物理驱动模型的可信度**；一旦需求被误读、或热-母线模型系统性偏乐观，系统会在**自洽但错误**的 `R_core` 与 `E_core` 上签发“可兑现”证书，于任务中段遭遇静默降额，既没做对用户要的事、又让全身控制器在真实包络之外发力——因此必须以 **must 项强制确认 + 包络保守外近似 + 热裕度硬约束 + 效用有界协商** 四重护栏，宁可分级降级或请求用户，绝不把“需求听起来合理”与“驱动此刻够用”当作“任务一定能兑现”。
