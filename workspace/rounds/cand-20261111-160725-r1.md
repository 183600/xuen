# 第 55 轮（承接第 54 轮 v31 GroundEdge-GenSim+++；新灵感循环第 1 轮；本轮灵感：「容错控制」×「论文发表」）

> 第 54 轮把技能组合从“能力匹配”推进为动作-鲁棒性双证书 `J=(ρ,A_cert,γ_ce,δ_a)`。本轮引入两个外部视角：控制论的 **容错控制（FTC）** 与科学社会学的 **论文发表（可复现/可证伪）**。核心矛盾：**H22**：现有 `ρ/α_S/J` 只覆盖参数扰动与动作扰动，未对**部件故障模式**建模，证书在传感器失效、执行器卡死、通信掉线时可能给出“假 valid”；**H23**：以成功率为主的发表证据链允许**选择性报告**，缺少预先登记的反例协议，导致“可发表”与“可部署”脱钩。

## 0. 直觉与动机

**灵感 1（故障剖面 → 与动作剖面同构的第二维）**
直觉：若技能是动作空间占用 `α_S : A→[0,1]`，则它同样在故障空间 `F` 上有占用 `β_S : F→[0,1]`：`β_S(f)=1` 表示技能在故障 `f` 下仍满足契约。组合前必须先做 **故障覆盖检查** `cover_F(S,F_T)`，否则动作兼容只是“健康状态下的兼容”。这把容错从运行时补丁前移为组合的第一性约束，与第 54 轮 `cover(S,A_T)` 形成对偶。

**灵感 2（被动不变集 + 主动重构 → 两类容错证书）**
直觉：FTC 分被动/主动。被动容错 = 在动作空间内找 **鲁棒不变包络** `E_S`，使有界故障下仍不越安全边界；主动容错 = 故障检测与诊断（FDD）后在技能组合图 `G_S` 上**重选路径** `π_rec`。证书必须显式区分“我保证不坏”(passive) 与“我坏了能换”(active)，二者不可互相冒充，否则会把重构能力记成鲁棒能力。

**灵感 3（退化阶梯 → 把“降级”写成契约而非事故）**
直觉：容错系统的优雅降级应是有序的 `ℓ0` 正常 → `ℓ1` 降性能 → `ℓ2` 安全停 → `ℓ3` 失效可运行。每级有动作包络 `A_ℓ` 与鲁棒性下限 `ρ_ℓ`，且 `A_0 ⊇ A_1 ⊇ A_2 ⊇ A_3`。退化阶梯把“故障后还能做什么”变成可验证契约，并与第 54 轮的动作空间剖面直接接合：退化不是换一套技能，而是收缩同一个动作包络。

**灵感 4（审稿人 = 对抗故障注入器 → 可发表性作为可证伪性）**
直觉：把“论文发表”不当写作技巧，而当**证据制度**：可发表 ≜ 可复现 + 可证伪 + 可比较。审稿人本质是对抗性故障注入器 `R`，从分布 `D_review` 采样故障并检验 claim。系统应能自动生成 **证伪报告（negative result）** 作为一等产物；被拒绝的组合也产出可审计的“失败论文”，使系统性负结果可被发表、可被复用。

**灵感 5（四联证书融合与金字塔扩展）**
直觉：第 54 轮 `J` 之外再加 `FTCert` 与 `RAC`，形成 **故障-动作-鲁棒性-可发表四联证书** `FPC`。金字塔增加容断层 `𝔽`：`𝔽0` 物理故障极限、`𝔽1` 故障剖面、`𝔽2` 退化阶梯、`𝔽3` 审稿对抗证据。跨层传递必须同时携带“健康证明”和“故障证明”，缺一不可。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（故障模式空间与故障剖面）**
故障空间 `F = F_s × F_a × F_c × F_p`，分别为传感器、执行器、通信、规划器故障。技能 `S` 的故障剖面 `β_S : F→[0,1]`，`β_S(f)=1` 表示故障 `f` 下仍满足契约 `(α_S,ρ_S)`。**故障覆盖** `cover_F(S,F_T)=1 ⇔ ∀f∈F_T, β_S(f)≥θ_F`。与 `α_S` 的区别：`α_S` 描述“能对哪些动作负责”，`β_S` 描述“坏成什么样仍负责”。

**定义 122（容错证书 FTCert）**
`FTCert = (F_core, F_buffer, E_S, π_rec, T_rec, evidence)`：
- `F_core={f | β_S(f)≥θ_F}` 认证故障核心集；
- `F_buffer=F_T \ F_core` 容错带（必须由主动重构兜底）；
- `E_S ⊆ A×F` 被动鲁棒不变包络：`∀(a,f)∈E_S`，执行不越安全边界；
- `π_rec:(S,F)→(S',path)` 主动重构策略，`T_rec` 为重构时延上界；
- `evidence` 含故障注入轨迹与诊断日志。
要求 `A_core(S) ⊆ proj_A(E_S)`，从而与第 54 轮 `A_cert` 对齐。

**定义 123（可检测性与可隔离性）**
检测器 `D` 对故障 `f`：`d_D(f)=P(alarm within τ_d | f)`，`ι_D(f)=P(ĥ=f | alarm,f)`。故障可认证当 `d_D(f)≥θ_d ∧ ι_D(f)≥θ_i`；否则只能进 `F_buffer` 并默认 `safe-stop`。误报率 `ε_FA=P(alarm | no fault)`。注意：**不可诊断的故障不得记入 `F_core`**，这是防止“容错证书自我拔高”的关键闸门。

**定义 124（退化阶梯）**
`L=(ℓ_0,...,ℓ_3)`，每级 `C_ℓ=(A_ℓ,ρ_ℓ,T_ℓ)`。要求：
```
A_0 ⊇ A_1 ⊇ A_2 ⊇ A_3,  A_3 ≠ ∅,  A_2 ⊆ A_safe,
perf(A_1) ≥ (1-δ_deg)·perf(A_0),  T_stop ≤ T_max
```
契约 `C_deg` 为满足上述条件的 `L` 集合。退化阶梯与动作剖面共用同一个 `A`，因此可与 `α_S` 的阈值 `θ_cov` 逐级求交。

**定义 125（审稿人对抗证书 RAC）**
`RAC=(claim,E,Φ,h,N,η,B,A)`：`claim` 为可检验断言（如“部署成功率 ≥ p”）；`E` 为证据；`Φ` 为**预先登记**的证伪协议（`D_review`、样本量、停止规则）；`h` 为制品哈希；`N` 为统计功效；`η` 为允许假证书率；`B` 基线；`A` 消融。定义：
```
publishable(RAC) ⇔ false_cert_rate(Φ) ≤ η ∧ rebuild(h)=1 ∧ claim_matches(E)
```
其中 `false_cert_rate` 是证书判 `ok` 但真实故障下失败的频率。

**定义 126（故障-可发表联合证书 FPC 与“双门槛分离”）**
`FPC=(J,FTCert,RAC,F_T,η)`。定义：
```
deployable ⇔ dom_J(T)=in ∧ δ_a<Θ_a ∧ cover_F(β_S,F_T)
             ∧ monotone(L) ∧ P(false cert)≤η
publishable ⇔ RAC.publishable
```
两者**刻意不合并**：只满足 deployable 标“可部署但证据不足”，只满足 publishable 标“可发表但仅健康域”。联合证书为 `FPC` 当其同时满足两者；否则输出带标签的偏序状态，禁止用发表指标反推部署安全。

## 2. 关键算法 伪代码

### IP-121 FMC（Fault Mode Characterization）

```python
def fault_profile(skill, F, injector, contract):
    beta = {}
    for f in F:
        trace = injector.run(skill, f)
        beta[f] = 1.0 if contract.satisfied(trace) else 0.0
    return beta

def cover_F(beta, F_T, theta_F=0.9):
    return all(beta.get(f, 0.0) >= theta_F for f in F_T)
```

### IP-122 FTC（Fault-Tolerant Certificate）

```python
def fault_tolerant_certificate(skill, F_T, alpha, rho, rho_min, T_stop):
    beta = fault_profile(skill, F_T, injector, skill.contract)
    F_core = {f for f in F_T if beta[f] >= theta_F}
    E = robust_invariant_envelope(skill, F_core)          # (a,f) 不越安全边界
    ladder = build_degradation_ladder(skill, beta, alpha, rho)
    if not monotone(ladder) or not safe_stop_reachable(skill, T_stop):
        return ('reject', 'ladder_violation')
    if not proj_A(E).issuperset(skill.A_core):
        return ('reject', 'passive_envelope_gap')
    return ('ok', FTCert(F_core, F_T - F_core, E, skill.pi_rec, T_stop, beta))
```

### IP-123 FDD Gate（检测-隔离闸门）

```python
def fdd_gate(obs, detector, tau_d, theta_d, theta_i):
    if not detector.alarm_within(obs, tau_d):
        return ('no_alarm', None)
    f_hat = detector.isolate(obs)
    if detector.detect_prob[f_hat] < theta_d or detector.iso_prob[f_hat] < theta_i:
        return ('ambiguous', f_hat)          # 只能 safe-stop，不得认证
    return ('diagnosed', f_hat)
```

### IP-124 AFT（Active Fault-Tolerant Reconfiguration）

```python
def active_reconfigure(cur, task, f_hat, G_S, FTCerts, tau_rec):
    t0 = now()
    allowed = [S for S in G_S.nodes
               if f_hat in FTCerts[S].F_core and compat_ok(cur, S)]
    path = a_star(G_S, start=cur, goal=task, allowed=allowed,
                  budget=tau_rec, cost=cost_align)
    if path is None or now() - t0 > tau_rec:
        return ('safe_stop', degrade_to(cur, level=2))
    return ('reconfigured', path, now() - t0)
```

### IP-125 RAA（Reviewer-Adversarial Audit）

```python
def reviewer_adversarial_audit(cert, claim, D_review, N, eta):
    violations = 0
    for _ in range(N):
        f = D_review.sample()
        ok = claim_holds(injector.run(cert.skill, f), claim)
        if cert.says_ok(f) and not ok:
            violations += 1                      # 证书-现实不一致
    p_false = violations / N
    reproducible = artifact.check_hash(cert.hash) and ci.rebuild_ok(cert.artifact)
    if p_false <= eta and reproducible and claim_matches(cert.evidence, claim):
        return ('publishable', p_false, reproducible)
    return ('reject', p_false, reproducible)
```

### IP-126 FPC（Fault-Publication Certificate）

```python
def fault_publication_certificate(J, ftcert, claim, D_review, F_T, eta):
    if not cover_F(ftcert.beta, F_T):
        return ('reject', 'fault_coverage_gap')
    if not monotone(ftcert.ladder):
        return ('reject', 'ladder_violation')
    stat = reviewer_adversarial_audit(ftcert, claim, D_review, N, eta)
    if stat[0] != 'publishable':
        return ('reject', 'publication', stat)
    deploy = deployable(J, ftcert) and (stat[1] <= eta)
    label = 'deployable+publishable' if deploy else 'publishable_only_healthy_domain'
    return (label, FPC(J, ftcert, stat, claim.hash))
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| FMC | `O(|F|·|A|·T_sim)` | `O(|F|)` | 故障采样覆盖、注入可复现 |
| FTC | `O(|F|·|A| + |A|·|L|)` | `O(|A|·|F|)` | 不变包络 sound、阶梯单调 |
| FDD | `O(|obs|)` + 诊断表 | `O(|obs|)` | `d,ι` 校准、误报受控 |
| AFT | `O(|V| log|V| + |E|)` | `O(|V|+|E|)` | 候选集只含 `F_core` |
| RAA | `O(N·T_sim + |claim|)` | `O(N)` | 协议预登记、无 p-hacking |
| FPC | `O(FTC + RAA)` | `O(|F|+N)` | 双门槛分离、标签诚实 |

**正确性定理（Fault-Tolerant Publication Soundness, FTPS）**
承接第 54 轮 (A22)–(A28)，新增：
**(A29)** `F_T` 以 `ε_F` 覆盖真实故障空间：`sup_{f∈F} min_{f'∈F_T} d(f,f') ≤ ε_F`；
**(A30)** 对 `f∈F_core`，`d_D(f)≥θ_d`、`ι_D(f)≥θ_i`、`ε_FA≤θ_FA`，且 `τ_d+τ_rec≤T_max`；
**(A31)** 阶梯合法：`A_0⊇...⊇A_3`、`A_3≠∅`、`A_2⊆A_safe`、`T_stop≤T_max`；
**(A32)** `TV(D_review,D_deploy)≤ε_R`，且制品可复现（`rebuild=1`）。
则：
```
P(success ∧ cert truthful) ≥ 1 - Σ_d(1-ρ_min(d)) - β_E - P(δ_a>Θ_a)
                              - P_undet - ε_FA - ε_R
```
其中 `P_undet = Σ_{f∈F} π(f)·(1 - d_D(f)·ι_D(f))`。关键：**部署 soundness 依赖故障语料覆盖 ε_F；发表 soundness 额外依赖审稿分布与部署分布的差距 ε_R**。二者任一大，证书都只是“自洽的叙事”，不是“对世界的断言”。

## 4. 实验设计 E162–E166

| 实验 | 指标 | 目标 |
|---|---|---|
| E162 故障剖面准确度 | `|β_S - β_real|`；故障语料覆盖率 | MAE ≤ 0.05；覆盖 ≥ 90% |
| E163 FDD 时延与准确度 | P95 检测时延；检测率/隔离率；误报率 | ≤ 100ms；≥ 95% / ≥ 90%；≤ 3% |
| E164 退化阶梯有效性 | safe-stop 可达率；ℓ1 性能保持 | 100%；≥ 80% |
| E165 对抗假证书率 | `false_cert_rate`（RAA）vs 仅 ρ 基线 | ≤ 5%，较基线降 ≥ 15% |
| E166 可复现性 | 制品重建成功率；claim-evidence 一致率；审稿方差 | 100%；≥ 98%；跨审稿人 σ 小 |

补充：E166 采用“预登记 + 留出故障集 + 外部红队”三件套；所有失败组合自动生成 negative-result 报告，作为可发表的证伪证据。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 故障语料与真实故障分布错配 | 高 | 开放世界故障发现 + 主动注入 + 外部红队 + 定期补语料 |
| FDD 误诊/漏诊导致错误重构 | 高 | 歧义即 safe-stop；置信度门槛；重构后二次校验 |
| 退化阶梯契约爆炸 | 中 | 分层分解 + 只对关键动作建包络 |
| 审稿分布被作者过拟合（自审自过） | 高 | 预登记 + 留出集 + 第三方复现 + 接受负结果 |
| 可复现性漂移 | 中 | 制品哈希 + 环境钉死 + CI 重建门禁 |
| 重构震荡/频繁切换 | 中 | hysteresis + 切换预算 + 冷启动锚点 |

## 6. 本轮最大风险

**一句话**：把“容错”写成证书、把“发表”写成对抗审计，看似把可靠性与证据链都形式化了，但二者共享同一个**分布假设**——故障语料 `F_T` 必须覆盖真实故障、审稿分布 `D_review` 必须逼近部署分布；一旦二者同源且被作者过拟合（自己造故障、自己当审稿人），`FPC` 就会退化为自我印证的闭环，此时“可发表且可部署”的强断言反而是最危险的假阳性，故必须以**外部故障生成 + 预登记留出集 + 负结果优先发表**把闭环撬开。

# 第 55 轮产物 · 创新点清单 v32：GroundEdge-FTCert（FMC×FTC×FDD×DGL×RAA×FPC）

> 承接第 54 轮产物 v31。本轮在动作-鲁棒性双证书之上，增加 **故障剖面、容错证书、检测-隔离闸门、退化阶梯、审稿人对抗审计、故障-可发表联合证书** 六大算子：
> - **FMC（Fault Mode Characterization）**：技能故障剖面 `β_S:F→[0,1]`，与动作剖面 `α_S` 对偶；
> - **FTC（Fault-Tolerant Certificate）**：被动不变包络 `E_S` + 主动重构 `π_rec`，区分“不坏”与“能换”；
> - **FDD（Fault Detection & Diagnosis Gate）**：`(d,ι,ε_FA)` 认证闸门，歧义即安全停；
> - **DGL（Degradation Ladder）**：`ℓ0→ℓ3` 单调收缩的动作-鲁棒性契约；
> - **RAA（Reviewer-Adversarial Audit）**：预登记证伪协议 + 制品复现，把发表变成可证伪性；
> - **FPC（Fault-Publication Certificate）**：故障-动作-鲁棒性-可发表四联证书，部署与发表双门槛分离。
>
> IP 编号：IP-121~IP-126（共 6 个新增），升级 IP-118/120 以纳入故障维度与审稿证据。

```python
    ladder = build_degradation_ladder(skill, beta, alpha, rho)
    if not monotone(ladder) or not safe_stop_reachable(skill, T_stop):
        return ('reject', 'ladder_violation')
    if not proj_A(E).issuperset(skill.A_core):
        return ('reject', 'passive_envelope_gap')
    return ('ok', FTCert(F_core, F_T - F_core, E, skill.pi_rec, T_stop, beta))
```

```python
def build_degradation_ladder(skill, beta, alpha, rho):
    levels = []
    for l, (theta_cov_l, rho_min_l) in enumerate(LEVELS):   # ℓ0..ℓ3

    if not all(levels[i+1].A <= levels[i].A for i in range(len(levels)-1)):

    return levels

def active_reconfigure(cur, task, f_hat, G_S, FTCerts, tau_rec):

               if f_hat in FTCerts[S].F_core and compat_ok(cur, S)]
```

### IP-125 RAA

```python
def reviewer_adversarial_audit(cert, claim, D_review, N, eta):
    violations = 0
    for _ in range(N):
        f = D_review.sample()
        ok = claim_holds(injector.run(cert.skill, f), claim)
        if cert.says_ok(f) and not ok:
            violations += 1
    p_false = violations / N
    reproducible = artifact.check_hash(cert.hash) and ci.rebuild_ok(cert.artifact)
    if p_false <= eta and reproducible and claim_matches(cert.evidence, claim):
        return ('publishable', p_false, reproducible)
    return ('reject', p_false, reproducible)
```

```python
def fault_publication_certificate(J, ftcert, claim, D_review, F_T, eta):
    if not cover_F(ftcert.beta, F_T):
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| FMC | `O(|F|·|A|·T_sim)` | `O(|F|)` | 故障语料覆盖 ≥ 90%，注入可复现 |
| FTC | `O(|F|·|A|+|A|·|L|)` | `O(|A|·|F|)` | 不变包络 sound、阶梯单调 |
| FDD | `O(|obs|)` | `O(|obs|)` | `d,ι` 校准、误报受控 |
| DGL | `O(|A|·|L|)` | `O(|A|·|L|)` | 包络单调、safe-stop 可达 |
| RAA | `O(N·T_sim)` | `O(N)` | 协议预登记、留出集、无 p-hacking |
| FPC | `O(FTC+RAA)` | `O(|F|+N)` | 双门槛分离、标签诚实 |

**正确性定理（Fault-Tolerant Publication Soundness, FTPS）**
承接第 54 轮 (A22)–(A28)，新增 **(A29)** `F_T` 以 `ε_F` 覆盖真实故障空间；**(A30)** 对 `f∈F_core`，`d_D≥θ_d,ι_D≥θ_i,ε_FA≤θ_FA,τ_d+τ_rec≤T_max`；**(A31)** 阶梯合法（单调、非空、safe-stop 可达）；**(A32)** `TV(D_review,D_deploy)≤ε_R` 且制品可复现。
则：
```
P(success ∧ cert truthful) ≥ 1 - Σ_d(1-ρ_min(d)) - β_E - P(δ_a>Θ_a)
                              - P_undet - ε_FA - ε_R
```
其中 `P_undet = Σ_{f∈F} π(f)(1-d_D(f)·ι_D(f))`。关键：**部署 soundness 依赖 ε_F，发表 soundness 额外依赖 ε_R**；任何一项失效，证书都只是自洽叙事，而非对世界的断言。

## 6. 本轮最大风险

**一句话**：FMC/FTC/RAA 把容错与发表都形式化了，但二者共享同一分布假设——`F_T` 要覆盖真实故障、`D_review` 要逼近部署分布；若故障生成与审稿都由作者同源完成并被过拟合，`FPC` 会退化为自我印证闭环，“可发表且可部署”反而成为最危险的假阳性，故必须以**外部故障生成 + 预登记留出集 + 负结果优先发表**撬开这一闭环。
