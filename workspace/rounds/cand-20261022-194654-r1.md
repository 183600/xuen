# 想法区 · 第 9 轮（新循环 · 第 1 轮）：把「谁先做」交给释放地平线

**灵感词**：worst-case analysis / specification refinement / 鲁棒性
**起点**：v1.8「X-DUB/PACE-D*」。38 例 273→187→172 节点，deep 3,216→1,792→1,042，held-out 50 例 10,916→7,095→6,016（37 胜 13 平 0 负）；hard3#5 216→115，但根仍未闭。v1.8 的收官风险写得很清楚：**DCD 只在「同时就绪、等时长、等资格、未来集真包含、且包含者不更晚释放」时生效；四项缺一，分支因子回到 d。**

本轮是新一轮的第 1 轮，但我不打算推倒 v1.8。我想回答一个更窄、也更硬的问题：

> **在这四个条件里，哪一个才是真正的瓶颈？如果只能推翻一个，应该推翻哪一个？**

## 一、先做 worst-case 归因：四个条件各自值多少

DCD 的支配式是

```text
i ≼ j  ⟺  p_i=p_j ∧ E_i=E_j ∧ D_σ(i)⊆D_σ(j) ∧ est_j≤est_i .
```

它同时要求 `p` 相等、`E` 相等、后代集包含、释放不更晚。要判断哪一条最贵，最直接的办法是造**不可靠的 oracle**：故意删掉一条条件，看节点数能降到多少。这些 oracle 不能发货（没有证明），但它们给出「上界」。

deep suite 上（v1.8 = 1,042 节点）：

| 变体（均带 HPACK） | 删掉的条件 | deep 节点 | 相对 v1.8 | 能不能证明 |
|---|---|---:|---:|---|
| DCD | — | 1,042 | 1.00× | 能（v1.8 定理 1） |
| `noest` | 删 `est_j≤est_i` | 807 | 1.29× | 不能 |
| `noest_nop` | 再删 `p_i=p_j` | 231 | 4.51× | 明显不能 |
| `est_ge` | 把 `est` 反过来 | 1,330 | 0.78× | 不能（v1.8 已否） |

两个事实（都在**保留 `D`** 的前提下）：

1. **`est` 和 `p` 是大头。** 只放松 `est` 就能拿 1.29×；把 `p` 也放松，才有 4.51×。`D` 本身不是本轮的对象——v1.8 的直接后继消融显示，闭包相对 depth-1 值 1.113×。
2. **`est` 的反方向是负收益。** `est_ge` 在 hard3#5 上碰巧也是 115，但在 deep 上退化到 1,330（38 例合计仍是 172，没有净收益）。v1.8 当时说「60k 随机无反例但没有证明，不发货」——这个决定是对的：它不是一条被证伪的规则，而是一条**只在 NO 实例上碰巧不改变答案**的规则。

但这两个 oracle 都是「删条件」。真正有意思的是反过来：**不删 `est`，把 `est` 变成判据**。RHD 就是这么做的，它在 deep 上 sound 地拿到 4.415×，几乎追平那个 4.51× 的不可靠 oracle。

所以问题收窄成：

> **能不能找到一种新的交换，使 `est` 从「必须先满足的障碍」变成「判据本身」？**

## 二、转折：不是换槽，是插入

v1.8 的交换引理是**换槽**：i 和 j 的时间槽整体互换。它要求 `p_i=p_j`（槽长相同）、`E_i=E_j`（互相能上对方的机器）、`D_i⊆D_j`（i 的后代都能被 j 的提前完成覆盖），还要求 `est_j≤est_i`（j 不晚于 i 释放）。这四条都是「换槽」这个操作带来的，不是问题本身带来的。

如果改成**插入**呢？

设 `i,j` 同时就绪，且

```text
est_i + p_i ≤ est_j .
```

也就是说：i 在 j 被释放之前就能整个做完。考虑任一可行排程 S，且 S 的第一个任务是 j。j 的开始 `s_j ≥ est_j ≥ est_i+p_i`。既然 j 是第一个任务，**在 s_j 之前所有机器都是空的**；于是把 i 插到 `[est_i, est_i+p_i)`（选 i 的资格集里最早空闲的那台机器），再把 i 从它原来的位置删掉。

- 机器：插入区间在所有任务开始之前，空闲；删除 i 只会多出一个空槽。
- 释放：i 在 est_i 开始；j 的开始不动（仍 ≥ est_j）。
- 优先：i 的前驱在 σ 已完成；i 比原来更早完成，它的后继只会更松。
- 期限：i 更早，j 不动。
- 资格：插入用的是 i 自己的机器，不要求 j 能上。

**没有 `p_i=p_j`，没有 `E_i=E_j`，没有 `D_i⊆D_j`。** 唯一的要求是「i 能在 j 释放之前做完」。

一句话直觉：**如果一张短任务能在另一张任务释放之前整个塞进空闲前缀，那后者就不必是第一个。**

## 三、形式化：释放地平线 v(σ)

在状态 `σ=(R,A,est)` 上，令

```text
v(σ) = min_{i∈READY(R)} ( est_i + p_i )        # 释放地平线
Min_R(σ) = { i ∈ READY(R) : est_i < v(σ) }      # 地平线之前释放的任务
```

`Min_R` 恰好是严格偏序

```text
j ≺_R i  ⟺  est_j + p_j ≤ est_i
```

的**极小元**：若 `est_i ≥ v`，取 `i* = argmin(est+p)`，则 `est_{i*}+p_{i*} = v ≤ est_i`，且 `i*≠i`（否则 `p_i≤0`）；反过来 `est_i < v` 时任何 j 都满足 `est_j+p_j ≥ v > est_i`。所以

```text
Min_R(σ) = { i : est_i < v(σ) } ,
```

一次 `min` 加一次过滤，`O(d)`，不需要两两比较。

关键的一步是**只用一棵 min 树就能算**：上式的 `v` 是对**所有** ready 任务取的，不需要排除 j 自己——因为 `est_j < est_j+p_j` 恒成立，argmin 永远不会被自己误删。

## 四、和 DCD 组合：两个商可以交换

v1.8 的分支集是 `Max_D(READY)`（DCD 偏序的极大元）。本轮的分支集是

```text
K(σ) = Max_D( Min_R(READY) ) .
```

这一定义合法，因为两个商**可交换**：

> 若 j 被 RHD 删掉（`est_j ≥ v`），i 被 RHD 保留（`est_i < v`），则 j 不可能 DCD-支配 i——DCD 支配要求 `est_j ≤ est_i`，于是 `est_j ≤ est_i < v ≤ est_j`，矛盾。

所以 `Max_D(READY) ∩ Min_R = Max_D(Min_R)`，RHD 可以先做，而且**缩小了 DCD 的输入**。实现上：

```text
v = min(est_i + p_i for i in READY)
READY' = [i in READY if est_i < v]
K = DCD_skyline(READY')
```

复杂度 `O(d)`（RHD）+ `O(d' log d' + d'·c·n/ω)`（DCD，`d'=|READY'|≤d`），**比 v1.8 只少不多**。

## 五、worst-case：唯一的死角是「同步释放」

分支因子的新上界：

```text
c(σ) = |K(σ)| ≤ d_R(σ) = #{ i : est_i < v(σ) } .
```

设 `i* = argmin(est+p)`，则 `v = est_{i*}+p_{i*} ≤ est_min + p_{i*}`，于是

```text
d_R ≤ #{ i : est_i − est_min < p_{i*} } .
```

也就是说：**只有落在 `[est_min, est_min+p_{i*})` 这个释放窗口里的任务才可能第一个被做。** 如果所有 ready 任务的 `est` 相同，则 `v = est + p_min`，所有任务都在窗口里，`d_R = d`——RHD 退化为恒等。

这个最坏情况是**可达的**：一个根，后面挂 k 条私有链，所有链头同时释放，`p` 两两不同、后代集两两不可比。在链头这一层，`est` 全相等（RHD 不动），`p` 全不同（DCD 不动），于是 `c = d = k`。我用 k=6 的状态验证过：`d=6, d_R=6, c=6`。

所以本轮的诚实结论是：

- **最坏复杂度没有变**，仍是线性扩展计数（指数级）。
- 但最坏情况从「任何实例」缩成了「同步释放的那一层」；只要释放错峰一个 `p_min`，窗口就塌缩。
- **根层永远是 RHD 的盲区**：所有 source 的 est 都是 0，`v = min p > 0`，所以根上 `Min_R = 全部 source`。hard3#5 的根只有 1 个 source，本轮 115→38 的收益全部来自中层；根证书依然没有。

## 七、负结果与差点发出去的 bug

### 7.1 没有 NORM，RHD 是假的（本轮最重要的一条）

插入引理要求 i 能真的在 `est_i` 开始。v1.8 的 `NORM` 把 `est_i` 抬到 `min_{k∈E_i} A_k`，所以 `est_i` 是可达的最早开始。**如果去掉 NORM，这条规则不成立。**

我在独立暴力搜索（显式 release、不做 NORM）里找到 3 个反例（7,702 例中）。最小那个：

```text
n=6, m=2
p    = [2,2,4,3,2,3]
pred = [[],[],[0],[0,2],[0,1],[0,1,2,3]]
E    = [[0],[0],[0],[1],[0,1],[1]]
rel  = [0,0,0,3,0,1],  h=13
```

在状态 `A=(2,0), est=(·,0,2,3,2,2), READY={1,2}` 上，未归一化的 RHD 看到 `est_1+p_1=0+2=2 ≤ est_2=2`，于是删掉任务 2；但任务 1 的资格只有机器 0，机器 0 要到 2 才空，任务 1 实际 2–4 完成，把任务 2 推迟到 4–8，导致假 NO。NORM 后 `est_1=2`，`v=4`，两个都保留，可行。

这条不是实现 bug，是**规格 bug**：RHD 的定理必须写成「在 NORM 不变的 state 上」。所以 v1.9 在 `rhd=True` 时强制 `normalize=True`；这也提醒以后任何「把 est 调紧」的优化都必须重新证。

### 7.2 两边形 TSD：方向对了，但被 RHD 完全吸收

在想到 RHD 之前，我先试了「两边形」：保留 DCD 的 `D_i⊆D_j`，再加一条反向的 gap 规则 `est_i+p_i ≤ est_j` 时删 j。deep 上 1,042→**682**，hard3#5 不变。它是 RHD 的**特例**（RHD 不需要 D），所以最终被 RHD 吸收（RHD 单独 353，组合 236）。

它还有一个实现陷阱：`D` 相等且 `est` 相等时，`dom(j,i)` 和 `dom(i,j)` 会同时为真，两个都被删。这个 bug 让 hard3#2 在 `h=OPT` 假 NO，是被「h=OPT 必须 YES」的断言抓出来的，不是被 NO 侧对拍抓出来的。教训和 v1.8 的 skyline 驱逐 bug 一样：**NO 侧对拍只能证明「两边都 NO」，不能证明「商是对的」。**

### 7.3 `p` 放松的 4.51×：看得见，但不敢拿

`noest_nop`（同时删 est 和 p）在 deep 上 231，相对 v1.8 是 4.51×；但 RHD 组合已经是 236，只差 **1.02×**。也就是说，本轮的 4.415× 已经把这个「删 est + 删 p」的 oracle 头程吃掉了 98%。它显然没有交换证明——槽长不同，插进去会把后面的任务顶开。**在 deep 上，p 放松的剩余空间很小**；在别的实例族上可能还有，但不能拿 deep 的 4.51× 当成本轮的剩余收益。

### 7.4 能量尾部仍然零效果

v1.8 的 `q^E` 在 hard3#5 和 deep 上逐字不变；本轮没有再碰。RHD 的收益不来自能量，而来自「谁能第一个做」的顺序商，两者正交。

## 八、一句话最大风险

**RHD 的收益全部来自「释放错峰」；只要某一层的 ready 任务同时释放（根层、单根扇出层、或所有机器同时空闲），`Min_R` 就等于 `READY`，分支因子回到 DCD 的 c，最坏情况仍是 n!，而 hard3#5 的根证书依然没有。**

# 产物区 · v1.9：X-DUB/PACE-R*

> PACE-R = PACE with **R**elease-horizon dominance。
> 在 v1.8 的 `DCD`（后代闭包支配）、`ODOM`（交换类）、`HPACK`（强制重叠装箱）之上，本轮只加一层：
> **tier 0.25 `RHD`（Release-Horizon Dominance，释放地平线支配）**：在 DCD 之前，只保留在**最早可能完成时刻**之前释放的 ready 任务。
> 中文名：**释放地平线支配引擎**。
> 状态：设计稿 + 可运行实现 + 38 例主实验 + 8 例 deep + 50 例 held-out + 40 例 DCD-必死对抗 + 60 例 easy + 9,000 组随机对拍 + **111,053 例穷举对拍** + **30,000 例显式 release 的独立暴力对拍** + 30,000 状态组合商单测，全部 0 不一致；未接 PSPLIB，未做形式化验证，n≥22 未系统测试。

## 0. 版本关系与本轮增量

v1.8 的资产全部保留：`DCD`、`ODOM`、`HPACK`、`PACK-front`、`LC-PACK` 的 0/0.5/1/2/3 层、`LC-DEC`、`CHECK-LC`、`PROFILE`、`(est,A)` Pareto 前沿 `G`、孪生机器商 `CANON`、`FRONT`/`FRONT-SUB`/`NO-INT` 证书、`MINT`、`PACK-SET`、`SOP`、carry 定理。

本轮增量：

1. **`RHD`（tier 0.25）**：定义释放地平线 `v(σ)=min_{i∈READY}(est_i+p_i)`，只分支 `Min_R(σ)={i:est_i<v(σ)}`。
2. **一条新的交换引理（插入，不是换槽）**：若 `est_i+p_i≤est_j`，则任一以 j 开头的可行排程都可改成以 i 开头；**不要求 `p_i=p_j`、不要求 `E_i=E_j`、不要求 `D_i⊆D_j`**。
3. **两个商可交换**：`Max_D(Min_R(READY)) = Max_D(READY) ∩ Min_R`；RHD 先做，并把 DCD 的输入从 d 缩到 `d_R`。
4. **一个可计算的分支上界**：`c=|K|≤d_R≤#{i:est_i−est_min<p_{i*}}`；同步释放时取等，构造出 `c=d` 的紧例子。
5. **实验**：38 例 172→**95**；deep 1,042→**236**（4.415× over v1.8，13.63× over v1.6）；held-out 6,016→**2,332**（2.580×，44 胜 6 平 0 负）；hard3#5 115→**38**；DCD-必死的 distinct-p 上 **3.024×**（DCD 丢弃数按构造成 0）。
6. **一个必须写进规格的前提**：没有 `NORM`，RHD 是**假的**（7,702 例显式 release 里 3 个反例）；有 `NORM`，30,000 例 0 反例。`rhd=True` 时强制 `normalize=True`。
7. **三个负结果**：删 `est` 的 oracle 807 但不可靠；删 `p` 的 oracle 231（4.51× vs v1.8，但 v1.9 的 236 只差 1.02×）没有证明；两边形 TSD 682 被 RHD 完全吸收。

退化关系：

```text
关 RHD（保留 DCD+HPACK）                 → 逐字回到 v1.8 的 172 / 1,042
关 DCD（保留 RHD+HPACK）                 → 118 / 353
RHD 关、DCD 关、HPACK 关                 → 逐字回到 v1.6 的 273 / 3,216
把 RHD 的 `normalize` 关掉               → 不合法；显式 release 下有反例
把 RHD 换成「删 est 条件」的 oracle       → 146 / 807，不可靠，不发货
把 RHD 换成两边形 TSD（带 D 的 gap）      → 172 / 682，被 RHD 吸收
```

## 1. 符号

| 符号 | 含义 |
|---|---|
| `I=(n,m,p,E,≺,h)` | 实例：加工时间、资格、优先图、公共期限 |
| `σ=(R,A,est)` | DEC 状态：未调度集、机器可用时刻、最早开始 |
| `Ready(R)` | `{i∈R : pred(i)∩R=∅}` |
| `ā_i` | `min_{k∈E_i} A_k`，i 的最早可用机器时刻 |
| `v(σ)` | 释放地平线 `min_{i∈Ready}(est_i+p_i)` |
| `≺_R` | 释放-完成严格偏序：`j≺_R i ⟺ est_j+p_j≤est_i` |
| `Min_R(σ)` | `≺_R` 在 `Ready(R)` 上的极小元集 |
| `D_σ(i)` | 残余图里 i 的严格后裔集（v1.8） |
| `≼_D` | DCD 支配预序（v1.8） |
| `Max_D(S)` | `≼_D` 在 S 上的极大元集 |
| `K(σ)` | `Max_D(Min_R(Ready))`，本轮分支集 |
| `d` | `|Ready(R)|` |
| `d_R` | `|Min_R(σ)|` |
| `c` | `|K(σ)|` |
| `q_i` | i 到 R 内汇点的最长路（不含 p_i） |
| `ω` | 机器字长，64 |

## 2. 形式定义

### 2.1 NORM 不变式

**定义 1（NORM 状态）**。称 `σ=(R,A,est)` 是 NORM 的，若

```text
∀i∈R :  est_i ≥ ā_i(A) = min_{k∈E_i} A_k .
```

`NORM` 把所有低于机器可用时刻的 inactive release 抬到 `ā_i`。这是一个等价状态：任何可行排程本来就不可能让 i 在 `ā_i` 之前开始，所以抬高 est 不改变可行集。

**这就是 RHD 的规格前提。** 没有它，插入引理的第 1 步（i 能在 `est_i` 开始）不成立；6.1 给出反例。

### 2.2 释放地平线

**定义 2（释放地平线）**。

```text
v(σ) = min_{i∈Ready(R)} ( est_i + p_i ) .
```

它是在当前状态里，**任何** ready 任务最早可能的完成时刻。注意它是对全部 ready 取的，不排除任何任务；`v` 只依赖 `(est,p)`，O(d)。

### 2.3 释放-完成序

**定义 3（≺_R）**。

```text
j ≺_R i  ⟺  est_j + p_j ≤ est_i .
```

**引理 1（严格偏序）**。`≺_R` 是非自反、传递的。

**证明**。非自反：`est_j+p_j≤est_j` 要求 `p_j≤0`，而 `p_j≥1`。传递：`est_j+p_j≤est_i` 且 `est_i+p_i≤est_k` ⇒ `est_j+p_j≤est_k−p_i<est_k`。∎

`≺_R` 的直觉：j 不仅比 i 早释放，而且**早到能在 i 释放之前整个做完**。

### 2.4 极小元

**引理 2（阈值表示）**。

```text
Min_R(σ) := {i∈Ready : ¬∃j∈Ready, j≠i, est_j+p_j≤est_i}
          = {i∈Ready : est_i < v(σ)} .
```

**证明**。

- 若 `est_i<v`：任意 j 有 `est_j+p_j≥v>est_i`，无见证，i 是极小元。
- 若 `est_i≥v`：取 `i*=argmin(est+p)`，则 `est_{i*}+p_{i*}=v≤est_i`。若 `i*=i`，则 `est_i+p_i=v≤est_i`，即 `p_i≤0`，矛盾；故 `i*≠i` 是见证，i 不是极小元。∎

所以 `Min_R` 是**一次 min + 一次过滤**，不需要两两比较，也不需要第二小值。

### 2.5 分支集与正规形

**定义 4（RHD 分支集）**。

```text
K(σ) = Max_D( Min_R(Ready(R)) ) .
```

**定义 5（RHD 正规形）**。从 σ 出发的排程是 RHD-正规的，若它开始最早的任务属于 `K(σ)`，且删除该任务后的残余排程在相应子状态下正规（递归定义，与 v1.8 同构）。

### 2.6 与 v1.8 的关系

- 若所有 ready 任务的 est 相同，则 `v=est+min p`，`est_i<v` 对所有 i 成立，`Min_R=Ready`，`K=Max_D(Ready)`：**RHD 退化为恒等，逐字回到 v1.8**。
- 若 `p` 两两不同，DCD 的 `p_i=p_j` 永远不成立，`Max_D` 退化为恒等，`K=Min_R`：**RHD 单独工作**。

## 3. 算法

### 3.1 每节点 RHD

```text
RHD(ready, p, est):
    v ← min_{i∈ready} (est_i + p_i)        # O(d)
    return [ i∈ready : est_i < v ]        # O(d)
```

不需要排序，不需要位集，不需要两两比较。

### 3.2 与 DCD 组合

```text
K(σ):
    ready ← Ready(R)
    ready ← RHD(ready, p, est)             # tier 0.25
    K     ← DCD_skyline(ready)             # tier 0.3, v1.8 原样
    return K
```

组合的合法性由 4.3 的交换性引理保证；RHD 先做，DCD 的输入从 d 降到 `d_R`。

### 3.3 接进 PACE-R 的搜索

```text
PACE-R(σ,h):
  1  if R=∅: return YES([])
  2  if DEAD(σ): return NO
  3  σ←NORM(σ); A*←CANON(A); estt←est|R
  4  exact memo / F_sub / INT                            # v1.7，不变
  5  window 层: energy / clique / subset / HPACK          # v1.7，不变
  6  MINT / PACK-SET / SOP                                # v1.7，不变
  7  if ¬PACK(σ,h): F_pack.insert; return NO(PACK)        # v1.7，不变
  8  ready ← RHD(READY(R), p, est)                        # 本轮，tier 0.25
  9  K ← DCD(ready)                                       # 本轮组合，tier 0.3
 10  for i in K:
         for k in machines(i):
             t ← max(A_k,est_i)
             if t+p_i+q_i(R\{i}) > h: continue
             r ← PACE-R(child(i,k,t))
             if r=YES: return YES([(i,k,t)]+r)
 11  F_sub.insert(estt,A*); return NO(RESOLVE)
```

与 v1.8 的差异只有第 8–9 步：先 RHD 过滤，再 DCD 取极大元。第 10 步的 `machines(i)` 仍是 v1.6 的 `DISPATCH(i,σ)`（全资格）或 `E_i`（异资格）。

### 3.4 实现细节

- `rhd_branch_set(ready,p,est)` 返回 `(keep,drop)`；`v` 用一次 `min`，过滤一次。
- `rhd=True` 时在 `decide` 入口强制 `normalize=True`。这是**正确性要求**，不是优化。
- `dcd_branch_set` 接收的是 RHD 过滤后的 `ready`；`dcd_fan_before` 因此等于 `d_R`。
- 统计字段：`rhd_calls`、`rhd_drops`、`rhd_fan_before`、`rhd_fan_after`。
- 不新增记忆表；RHD 是无状态的每节点过滤。
- 消融开关：`rhd`（默认 False，v1.9 主配置 True）、`dcd_direct`（v1.8 遗留）。

## 4. 定理与证明

### 4.1 插入引理

**引理 3（insertion exchange）**。设 σ 是 NORM 状态，`i,j∈Ready(R)`，`i≠j`，且

```text
est_i + p_i ≤ est_j .
```

若存在从 σ 出发的可行排程 S，且 S 的第一个任务是 j，则存在从 σ 出发的可行排程 S'，其第一个任务是 i。

**证明**。设 S 中 j 的开始为 `s_j`。因为 j 是第一个任务，S 中没有任何任务在 `s_j` 之前开始；又 `s_j≥est_j≥est_i+p_i`，所以所有机器在 `[est_i,est_i+p_i)` 上都是空的。

取 `k*∈E_i` 使 `A_{k*}=ā_i`。NORM 给出 `ā_i≤est_i`，所以 k* 在 `est_i` 已可用。在 S' 中：

1. 把 i 插到机器 k* 的 `[est_i,est_i+p_i)`；
2. 把 i 从 S 中的原位置删掉（原开始 `s_i≥s_j≥est_i+p_i`，所以删除只会空出一个更晚的槽）。

逐项验证：

- **资格**：k*∈E_i。
- **释放**：i 在 `est_i` 开始。
- **机器**：插入区间在所有任务开始之前，空闲；删除 i 不产生重叠。
- **优先**：i 的前驱在 σ 已全部完成（i ready），完成时刻 ≤est_i；i 的新完成 `est_i+p_i≤s_j≤s_i`，而 i 的原完成后继只会更早，所以 i 的后继约束不紧于 S；其他任务的前驱完成时刻不变。
- **期限**：i 比原来早，其他不变。
- **makespan**：不变或更小。

且 `est_i<s_j`，所以 S' 的第一个任务是 i。∎

**注（为什么可以是插入而不是换槽）**。v1.8 的换槽要求两边槽长相同、资格相同、后代包含，是因为它交换的是**两个已占用的区间**。插入只占用一个**空闲前缀**，所以只要 i 自己能在 `est_i` 开始、并在 `est_j` 前结束，就不需要 j 的任何性质。

**注（NORM 不可省）**。若 `est_i<ā_i`，i 实际不能在 `est_i` 开始；插入会被推迟到 `ā_i`，可能越过 `est_j`，引理不成立。6.1 是最小反例。

### 4.2 极小元表示

**定理 1（Min_R 的阈值表示）**。`Min_R(σ)={i∈Ready:est_i<v(σ)}`，且 `Min_R≠∅`。

**证明**。引理 2 已证等式。非空：取 `i*=argmin(est+p)`，则 `est_{i*}<est_{i*}+p_{i*}=v`，故 `i*∈Min_R`。∎

### 4.3 交换性

**引理 4（commutation）**。对任意状态 σ，

```text
Max_D( Min_R(Ready) ) = Max_D(Ready) ∩ Min_R .
```

**证明**。

- `⊆`：设 `k∈Max_D(Min_R)`。显然 `k∈Min_R`。若 `k∉Max_D(Ready)`，存在 `d∈Ready` 使 `d≻_D k`，即 `D_k⊆D_d`、`p_d=p_k`、`E_d=E_k`、`est_d≤est_k`。由 `est_k<v` 得 `est_d<v`，故 `d∈Min_R`，与 k 在 `Min_R` 中极大矛盾。所以 `k∈Max_D(Ready)`。
- `⊇`：设 `k∈Max_D(Ready)∩Min_R`。若 k 在 `Min_R` 中不极大，存在 `d∈Min_R⊆Ready` 使 `d≻_D k`，与 k 在 Ready 中极大矛盾。∎

**推论 1**。`K(σ)⊆Max_D(Ready)`，即 v1.9 的分支集是 v1.8 分支集的子集。

### 4.4 组合完备性

**定理 2（RHD 完备性）**。若存在从 σ 出发的可行排程，则存在 RHD-正规形可行排程；PACE-R 只分支 `K(σ)` 是完备的。

**证明**。对 `|R|` 归纳。取任一可行 S，令 e 为 S 中开始最早的任务。

- **e∈Min_R**：由引理 4，若 e 不在 `Max_D(Min_R)`，存在 `d∈Min_R` 使 `d≻_D e`；v1.8 定理 1 的换槽把 S 改成以 d 开头的可行 S'。重复（DCD 链在 `Min_R` 内良基：等 est 时 D 严格增大，或索引减小），最终到 `K`。
- **e∉Min_R**：由定理 1，`i*=argmin(est+p)` 满足 `i*∈Min_R` 且 `est_{i*}+p_{i*}≤est_e`。引理 3 把 S 改成以 `i*` 开头的可行 S'。然后回到上一种情况。

在两种情况下，DFS 的第 10 步都把新首任务放在 `t=max(A_k,est)≤其在新排程中的开始`，子状态不晚于 S' 去掉该任务后的状态；由归纳，子树返回可行排程。∎

**注（为什么不需要全局正规形）**。与 v1.8 相同：只交换「当前状态的两个 ready 任务」，不碰非 ready 任务，避开「j 的未调度前驱可能晚于 s_i」的坑。

**注（派工序 ≠ 开始序）**。证明选的是「开始最早」的任务；DFS 的派工序列可以不同，但子状态把它放在不晚于 S 的位置，完备性只要求存在一条派工序重现正规形。

**注（公共期限）**。插入只让 i 更早、其他不变，所以只用 `C_i≤h`；没有用个体期限。若任务有各自期限，需要额外条件，和 v1.8 的 ODOM/DCD 一样要重证。

### 4.5 分支上界与紧性

**定理 3（release-window bound）**。设 `i*=argmin(est+p)`，则

```text
c(σ) = |K(σ)| ≤ d_R(σ) = #{i∈Ready : est_i < v(σ)}
     ≤ #{i∈Ready : est_i − est_min < p_{i*}} .
```

并且存在实例使 `c=d`。

**证明**。第一层由 `K⊆Min_R`。第二层：`v=est_{i*}+p_{i*}≤est_min+p_{i*}`；`est_i<v` 蕴含 `est_i−est_min<p_{i*}`。

紧性：取一个根，后面挂 k 条私有链，所有链头同时释放（同一父任务），`p` 两两不同，后代集两两不可比。在链头层：

- 所有 `est` 相等 ⇒ `v=est+min p`，每个链头 `est<v` ⇒ `Min_R=Ready`，`d_R=d=k`；
- `p` 两两不同 ⇒ DCD 的 `p_i=p_j` 全不成立 ⇒ `Max_D` 恒等；
- 所以 `c=d=k`。

我用 k=6 的状态直接验证过：`d=6, d_R=6, c=6`。∎

**推论 2（最坏情况）**。最坏复杂度仍是线性扩展计数（指数级）；最坏情况是「同步释放 + 未来两两不可比 + p 两两不同」。RHD 不改变它，只把发生条件从「任何实例」缩到「同步释放的那一层」。

### 4.6 子树 / 无回退

**定理 4（subtree）**。对任意状态 σ，

```text
K_v19(σ) ⊆ K_v18(σ) = Max_D(Ready) .
```

因此（不加 memo/front 的）v1.9 搜索树是 v1.8 搜索树的子树，节点数不超过 v1.8。

**证明**。由引理 4，`K_v19=Max_D(Min_R)=Max_D(Ready)∩Min_R⊆Max_D(Ready)`。对深度归纳。∎

**注（frontier 截断）**。v1.8 的 `F_sub` 有 `K=48` 截断，且 `F_pack`/`F_sub` 的插入顺序会随访问顺序变化；所以「子树」在无截断时是定理，在有截断时只是经验（随机对拍 9,000 例节点总数均不增；deep#4 的 RHD 单独是 54 vs DCD 52，但组合是 23）。

### 4.7 复杂度

设 `d=|Ready|`，`d_R=|Min_R|`，`c=|K|`，位集 n 位、字长 `ω=64`。

```text
RHD 每节点:
    min + 过滤          O(d)
    空间                O(d)

DCD（在 d_R 个任务上）:
    排序                O(d_R log d_R)
    包含测试            O(d_R·c) 次，每次 O(n/ω)
    最坏                O(d_R·c·n/ω + d_R log d_R)

合计（RHD+DCD）:
    O(d + d_R·c·n/ω + d_R log d_R)  ≤  O(d²·n/ω + d log d)
    （v1.8 的 DCD 成本；因为 d_R≤d 且 c≤d_R）

主搜索:
    N(σ) = 1 + Σ_{i∈K} N(σ_i)
    N ≤ 正规形前缀数 ≤ n·L_RHD
    最坏仍为指数；本轮不改变最坏复杂度
```

**成本位置**。RHD 是 O(d) 的，且它**缩小了 DCD 的输入**：deep 上 RHD 把每节点的 ready 数从 3.38 降到 2.33，DCD 的比较次数随之下降。所以本轮不是「加一层 O(d²) 换更少的节点」，而是「加一层 O(d) 让下一层更便宜」。easy 60 例上时间 0.1614→0.1608 s，验证了这一点。

两组对抗实例，n=13–16，m=3，**p 两两不同**，所以 DCD 的 `p_i=p_j` 永远不成立，DCD 丢弃数按构造为 0：

| 家族（20 例） | base | v1.8 | **v1.9** | v1.9/v1.8 | DCD 丢弃 | 胜负 |
|---|---:|---:|---:|---:|---:|---|
| distinct-p | 5,685 | 4,594 | **1,519** | 3.024× | **0** | 19 胜 1 平 0 负 |
| 单根扇出链 | 6,693 | 4,401 | **2,085** | 2.111× | **0** | 19 胜 1 平 0 负 |

distinct-p 的 1 个平局是 HPACK 根部闭合；其余 19 例 RHD 都有正收益。**这是本轮最想说明的一件事**：v1.8 的收官风险说「DCD 不触发时收益退化为 1×」，而 RHD 在 DCD 完全不触发时给出 3.024×。

单根扇出链的深度 1 是**同步**的：一个根之后，k 个链头同时释放，`est` 全相等，RHD 在这一层是恒等；2.111× 来自更深层的错峰。这个家族同时是 4.5 节紧性构造的实例化。

### 5.8 分支因子

|---|---:|---:|---:|---:|---:|---|
| 38 | 82 | 66 | 16 | 12 | 54 | 3.28→2.64→2.16 |
| deep | 395 | 273 | 122 | 45 | 228 | 3.38→2.33→1.95 |

## 6. 负结果与陷阱

### 6.1 没有 NORM，RHD 是假的

插入引理要求 i 能在 `est_i` 开始；NORM 保证 `est_i≥ā_i`。去掉 NORM 后，独立暴力搜索在 7,702 例中找到 3 个假 NO。最小反例：

```text
n=6, m=2
p    = [2,2,4,3,2,3]
pred = [[],[],[0],[0,2],[0,1],[0,1,2,3]]
E    = [[0],[0],[0],[1],[0,1],[1]]
rel  = [0,0,0,3,0,1],  h=13
```

在状态 `A=(2,0), est=(·,0,2,3,2,2), READY={1,2}` 上：

- 未归一化：`est_1+p_1=0+2=2≤est_2=2`，RHD 删任务 2；但任务 1 的资格只有机器 0，机器 0 要到 2 才空，任务 1 实际 2–4 完成，把任务 2 推到 4–8，导致假 NO。
- NORM 后：`est_1=2`，`v=min(4,6)=4`，两个都保留，可行。

**实现约束**：`rhd=True` 时强制 `normalize=True`。这不是可调参数。

### 6.2 删 `est` 的 oracle：807，但不可靠

`noest` 在 deep 上 1,042→807（1.29×），在 38 上 172→146。它让「大未来」的任务无视释放顺序先做，在 NO 实例上看起来很好；但 h=OPT 的 YES 侧没有证明，而且 v1.8 的 `est_ge` 已经在 deep 上退化到 1,330。**没找到反例 ≠ 定理**，这条不发货。

### 6.3 删 `p` 的 oracle：231（4.51×），没有交换证明

`noest_nop` 同时删 `est` 和 `p`，deep 1,042→231（相对 v1.8 4.51×）。但 RHD 组合已经是 236，只差 **1.02×**：本轮的 4.415× 已经把这个 oracle 的头程吃掉了 98%。而且槽长不同，插进去会把后面的任务顶开；没有 slack 条件就没有证明。**在 deep 上，p 放松的剩余空间很小**；它作为「下一步」保留，但不能拿 4.51× 当成本轮的剩余收益。

### 6.4 两边形 TSD：682，被 RHD 完全吸收

先试的是保留 `D_i⊆D_j`、加一条 `est_i+p_i≤est_j` 的反向 gap 规则：deep 1,042→682，38 例不变。它是 RHD 的**特例**（RHD 不需要 D），所以被吸收（RHD 单独 353、组合 236）。

它还有一个实现陷阱：`D` 和 `est` 都相等时，`dom(j,i)` 与 `dom(i,j)` 同时为真，两个都被删；这会让 hard3#2 在 `h=OPT` 假 NO。这个 bug 是被「h=OPT 必须 YES」的断言抓出来的，不是被 NO 侧对拍抓出来的。教训：**NO 侧对拍只能证明两边都 NO，不能证明商是对的**；必须有 YES 侧断言和独立暴力。

### 6.5 根层仍然是盲区

所有 source 的 `est=0`，`v=min p>0`，所以 `Min_R=Ready`。RHD 在根上恒等，hard3#5 的根仍然没有证书（38 节点 / 17 表，不是 1 节点的根闭）。要让根闭，仍然需要 v1.8 说的「固定位置强制段 + 残余能量」或「跨窗口联合装箱」，不是顺序商能解决的。

### 6.6 能量尾部仍然零效果

v1.8 的 `q^E` 在 hard3#5 和 deep 上逐字不变；本轮没有再碰。RHD 的收益来自顺序，不来自能量。

## 8. 已知风险

1. **最坏复杂度没变**：仍是线性扩展计数，指数级。同步释放 + 未来两两不可比 + p 两两不同时 `c=d`；k=6 的紧例子已验证。
2. **根层盲区**：所有 source 的 est=0，RHD 在根上恒等；hard3#5 的根证书依然没有（38 节点不是 1 节点根闭）。
3. **NORM 是硬前提**：没有它，7,702 例显式 release 中有 3 个假 NO；`rhd=True` 强制 `normalize=True`，未来任何「调紧 est」的优化都必须重新证。
4. **公共期限 h**：插入只用 `C_i≤h`；若任务有各自期限，需要额外条件，和 v1.8 的 ODOM/DCD 一样要重证。
5. **`est` 必须是「精确的最早开始」**：证明同时用到 (a) `est_i≥ā_i`（i 能在 est_i 开始）和 (b) `est_j` 是 j 开始的下界（`s_j≥est_j`）。把 `est_j` 高估会破坏 (b)——S 可能在 est_j 之前就启动 j；把 `est_i` 低估到 `ā_i` 以下会破坏 (a)——6.1 的反例。NORM 给出的恰好是精确值；任何对 est 的调高/调低都要重新证，不能当成单调优化。
6. **frontier 截断破坏严格子树单调性**：`K⊆K_v18` 是定理，但 `F_sub` 的 K=48 截断和访问顺序可能让节点数在个别实例上略增（deep#4 的 RHD 单独 54 vs DCD 52；组合 23）。
7. **收益高度依赖释放错峰**：distinct-p 的 3.024× 来自错峰；单根扇出链的深度 1 同步，RHD 在这一层是恒等。
8. **删 `p` 的 4.51× 是相对 v1.8 的 oracle 头程，不是剩余头程**：v1.9 的 236 已经追平到 1.02×；而且 `noest_nop` 的 231 没有证明、不能发货。带 slack 的 `p` 放松在 deep 上剩余空间很小，真正的空间要到别的实例族去找。
9. **held-out 不是全新样本**：它由 v1.8 的生成过程（seed 424242）重放，v1.9 没有在它上面调参，但它也不是本轮新采的。对抗两组是我设计的，不是盲测。
10. **规模**：n≤16，m=3，deep 只有 8 例；n≥22、m≥4、PSPLIB 未测。
11. **ODOM+RHD 组合只做了交换性证明，没有基准**：主配置是 DCD+RHD+HPACK，`odom=False`。
12. **时间常数是 Python 的**：0.0322 vs 0.0405 在 3 次中位数下稳定，但绝对时间不可移植；节点数与表数是确定性的。
13. **没有形式化验证**：9,000 随机 + 111,053 穷举 + 30,000 独立暴力 + 30,000 单测是很强的证据，但不是 Coq/Lean；定理 1–4、引理 1–4 是纸面证明。
14. **收益仍集中在 hard3#5**：216→38（v1.9），但 hard3 的其余 11 例、large_b、large_a、large_het 的 8 例逐字不变（large_het#1 仍是 21）。这不是普遍加速；38 例的 1.811× 几乎全部由一例贡献。
15. **单根扇出链不是纯最坏情况**：它的深度 1 同步，但更深层会错峰，所以 2.111× 不是「最坏情况的收益」，只是「DCD 必死时仍有收益」的证据。

## 9. 一句话最大风险

**RHD 的收益全部来自「释放错峰」；只要某一层的 ready 任务同时释放（根层、单根扇出层、或所有机器同时空闲），`Min_R` 就等于 `READY`，分支因子回到 DCD 的 c，最坏情况仍是 n!，而 hard3#5 的根证书依然没有。**
