# 想法区 · 第 8 轮：从 X-DUB/AG* 到 X-DUB/DC-LS

**灵感词**：减治 / local search / novel algorithm  
**起点**：v0.5「X-DUB/AG*」。它已经有一致 A*、贪心 focal、THRESH/DOM/INHERIT 证书泛化；本轮不推翻这些，而是补一个更基础的结构性缺口：**搜索树的粒度和 incumbent 的紧度没有耦合**。

## 一句话直觉：不是每个节点都值得“展开一个任务”；用 incumbent 把状态压成“必须执行的强制前缀”，再用关键路径局部搜索把 incumbent 压紧

v0.5 的减治只发生在证书层：THRESH 一次覆盖多个截止期、继承一次覆盖子树、支配一次覆盖状态。但**搜索树本身仍是“每个节点枚举一个 `(任务,机器)`”**。即使某个任务在 `U-1` 目标下已经被证明必须在某个时刻开始，v0.5 仍会把它当作一个分支枚举。更糟的是，v0.5 的 focal 只改变展开顺序，不改变树的宽度。

本轮把“减治”放到搜索树上，分三种粒度：

1. **REFUTE（减去子树）**：若存在任务 `i` 使 `est_i + p_i + q_i ≥ U`，则整个状态没有优于 `U` 的完成，直接剪掉子树。
2. **FORCED-SCHED（减去任务）**：若 `i` 就绪且 `est_i + p_i + q_i = U-1`，则 `i` 必须在该时刻开始；用机器支配规则唯一化机器选择，无分支调度，递归到不动点。
3. **MACH-DOM（减去兄弟分支）**：固定开始时间 `t` 时，若 `A_{k1} ≤ A_{k2} ≤ t`，则选 `A` 较大的 `k2` 支配 `k1`；每个任务-开始时间只保留一个机器分支。

这三条都只依赖 `U` 和当前状态的 head/tail，不需要训练、不需要窗口扫描；它们把一个 `|R|·m` 的分支因子压成“强制前缀 + 少量真正分支”。

Local search 补的是另一半：v0.5 的贪心 guide 只构造一次，没有改进。本轮在关键路径上做交换/跨机器插入，把 `U` 压紧。**`U` 越紧，`slack=0` 的任务越多，FORCED-SCHED 越强；这是一个正反馈。** LS 只用于上界和关键路径识别，不参与任何剪枝，所以它错得再多也只损失时间。

“Novel algorithm”不是再加一个启发式，而是把三者组合成一个可检查的减治搜索：REFUTE 减去整个子问题，FORCED-SCHED 减去一个任务，MACH-DOM 减去被支配的机器选择，LS 负责把 `U` 推向 OPT。证明 DAG 新增 `REFUTE`、`FORCED`、`MACH-DOM`、`LS-INCUMBENT` 四条局部规则。

## 三个灵感词分别补什么

- **减治**：REFUTE 减子树、FORCED-SCHED 减任务、MACH-DOM 减分支；三者的安全性都来自“目标 `makespan ≤ U-1`”这一前提。
- **Local search**：关键路径邻域（相邻交换、跨机器插入）改进 `U`；LS 的输出是可行调度和关键块，不是下界。
- **Novel algorithm**：把 v0.5 的“证书泛化”推进到“搜索树泛化”：不是证明更多 `H`，而是让搜索树本身在 `U` 紧时自动收缩。

## 核心方案：X-DUB/DC-LS

在 v0.5 上做四处增量：

1. **REFUTE**：对每个剩余任务计算

   ```text
   est_i   = max(lo_i, min_k A_k)
   slack_i = (U-1) - (est_i + p_i + q_i)
   ```

   若存在 `slack_i < 0`，状态无优于 `U` 的完成，剪枝。这是任务层的“减去子树”。

2. **FORCED-SCHED**：若 `i` 就绪且 `slack_i = 0`，则任何 `≤U-1` 的完成都必须让 `i` 在 `est_i` 开始；机器选择由 MACH-DOM 唯一化；调度 `i`，重新计算，直到没有可强制任务。若闭包完成，更新 `U`；若冲突，剪枝。

3. **MACH-DOM**：固定任务 `i` 和开始时间 `t`，若 `A_{k1} ≤ A_{k2} ≤ t`，则在 `k2` 上调度 `i` 得到的状态支配在 `k1` 上调度的状态；因此每个任务-开始时间只保留 `A` 最大的机器。

4. **LS-CRIT**：在 CP/LPT/MWKR 构造解上，对关键路径任务做同机器相邻交换和跨机器插入；只接受 makespan 严格下降的邻居；输出 `U_LS` 和关键块。只用于上界和 focal guide，不剪枝。

组合：

```text
L_LOC(σ) = max(L0, L_D, L_AV, L_TH)      # v0.5 不变
F(σ)     = max over path certificates     # v0.5 不变
f(σ)     = max(C(σ), F(σ))                # v0.5 不变
REDUCE(σ,U) → (dead | complete | σ')      # 本轮新增
```

搜索主循环只在“展开前”插入 `REDUCE`；其余 A* 一致性、focal、DOM-GEN、THRESH 全部保留。关闭 `REDUCE/LS`，退回 v0.5-lite。

## 本轮要验证的命题

1. **REFUTE 可采纳**：`slack_i<0 ⇒ OPT(σ)≥U`；剪掉整个子树不丢优于 `U` 的解。
2. **FORCED 可采纳**：`slack_i=0` 且 `i` 就绪 ⇒ 任何 `≤U-1` 的完成都让 `i` 在 `est_i` 开始；无分支调度不丢解。
3. **MACH-DOM 可采纳**：`A_{k1}≤A_{k2}≤t` ⇒ 在 `k2` 上调度 `i` 的状态支配 `k1`；由 DOM-GEN，`k1` 分支可剪。
4. **闭包终止且安全**：每次 FORCED-SCHED 减少一个剩余任务；冲突（`slack<0`）意味着无优于 `U` 的完成。
5. **LS 可行**：每个邻域操作经 decode 检查优先约束/机器不重叠；只接受严格改进，故 `U_LS` 可行且 `≤` 贪心 `U`。
6. **v0.5 可恢复**：关闭 REFUTE/FORCED/MACH-DOM/LS，恢复 v0.5-lite 的搜索语义。
7. **节点数**：在 43 个 `n=9–11`、`m=2–3` 的 DFS 对拍实例上，`mach+forced+ls` 的总扩展应显著低于 base，且所有变体返回相同 OPT。
8. **收益分解**：REFUTE（剪子树）与 FORCED-SCHED（减任务）各自贡献多少；LS 的边际贡献是否集中在 `U0` 较大的实例。
9. **负结果**：LS 是否真的增加根节点的强制任务数？如果否，说明“LS 压紧 `U` → 根强制更多”的直觉需要修正。

## 初步结果与边界

- **实例**：43 个 `n=9–11`、`m=2–3` 的随机 DAG，全部用独立 DFS 验证 OPT；12 个 `n=12–14`、`m=2` 的较大实例，用 base 闭合后的 `U` 作参考。共 55 个。
- **节点数（43 个 DFS 对拍实例）**：base 12,351；仅 REFUTE 3,607（−70.8%）；REFUTE+SCHED 3,246（−73.7%）；再加 MACH-DOM 2,890（−76.6%）；再加 LS 2,581（−79.1%）。所有变体 43/43 与 DFS 一致。
- **节点数（12 个较大实例）**：base 4,714；REFUTE 3,213（−31.8%）；REFUTE+SCHED 2,233（−52.6%）；`mach+forced+ls` 1,591（−66.2%）；所有变体闭合且 `U` 一致。
- **收益分解**：REFUTE 是主要来源（small −70.8%，big −31.8%）；SCHED 在 REFUTE 之上再减 10.0%/30.5%；MACH-DOM 单独约 −7.9%/−12.0%，但在 forced 之上只有 −11.0%/−2.4%；LS 在 forced 之上再减 10.7%/27.0%。
- **LS 的 `U` 改进**：small 18/43 实例严格改进，平均 1.05，最大 10；big 8/12，平均 2.17，最大 5。LS 单独只减 3.6%/18.2%，但与 forced 结合后边际收益明显。
- **重尾**：small 中 seed 95 一个实例贡献 7,390 次扩展（占 base 总量的 60%）；去掉它后，forced 的总减少从 73.7% 降到 44.3%，full 从 79.1% 降到 61.5%。big 中去掉最大实例 seed 19 后，forced 只剩 14.7%，full 仍有 59.9%。**减治是条件触发的，不是普遍加速。**
- **负结果**：根节点的强制调度数没有随 LS 的 `U` 改进而增加（small 0/43，big 仅 1/12）；LS 的收益主要来自更早的全局剪枝和少数直接闭合，而不是“根层强制更多”。这修正了本轮最初的直觉。
- **边界**：没有实现 THRESH-CERT 和完整 DOM-GEN Pareto 表，base 是 v0.5-lite（L0+AVAIL+inherit+focal+完全状态去重）；没有实现证明 DAG checker；没有 PSPLIB、`n>14`、`m>3`；LS 邻域只覆盖关键路径上的交换/插入；时间数据是纯 Python 单次测量。

## 本轮的一句话最大风险

**当前方案最大的风险是：减治的收益主要来自任务层 REFUTE 剪枝而非无分支调度，且高度重尾——在少数 `U` 接近 OPT 的困难实例上收益巨大，在多数实例上与 v0.5-lite 打平；一旦 `U` 不紧或优先约束不能转化为时间窗冲突，FORCED-SCHED 与 MACH-DOM 的收益会迅速消失，而 LS 和强制闭包的成本在更大规模上可能反超。**

# 产物区 · v0.6：X-DUB/DC-LS

> Decrease-and-conquer search with critical-path local search  
> 中文名：减治搜索 + 关键路径局部搜索  
> 状态：完整设计稿；43 个 `n=9–11`、`m=2–3` 的随机 DAG 与独立 DFS 对拍；12 个 `n=12–14` 的较大实例节点数/消融；证明 DAG checker、THRESH 完整组合、PSPLIB 规模实验留到下一轮。

---

## 0. 版本关系与本轮增量

v0.5（X-DUB/AG*）已经建立：

- `P|prec|Cmax` 的 `(任务,机器)` 动作空间与最优性覆盖；
- 时间价格对偶 `L_D`、AVAIL 异构打包核 `L_AV`、THRESH 截止期证书；
- 一致 A*：`F(σ)=max over path certificates`、`f(σ)=max(C(σ),F(σ))`；
- 贪心 focal guide、DOM-GEN 状态支配、INHERIT 路径继承；
- 证明 DAG 的局部检查规则。

v0.6 **不推翻**这些结论，只做五处增量：

1. **REFUTE**：任务层不可行性剪枝。若 `est_i+p_i+q_i ≥ U`，整个状态无优于 `U` 的完成，剪掉子树。
2. **FORCED-SCHED**：若 `i` 就绪且 `est_i+p_i+q_i = U-1`，则 `i` 被 incumbent 强制在 `est_i` 开始；无分支调度，递归到不动点。
3. **MACH-DOM**：固定开始时间 `t` 时，选择 `A_k` 最大的可用机器支配其他机器选择；每个任务-开始时间只保留一个机器分支。
4. **LS-CRIT**：关键路径局部搜索，改进 `U`、提取关键块；只用于上界和 guide，不参与剪枝。
5. **PROOF-DAG 扩展**：新增 `REFUTE`、`FORCED`、`MACH-DOM`、`LS-INCUMBENT` 四种局部规则。

关系：

```text
关闭 REFUTE/FORCED/MACH-DOM/LS       → v0.5-lite（本轮实验基线）
只开 REFUTE                          → 任务层剪枝
REFUTE + FORCED                      → 减治闭包
再加 MACH-DOM                        → 机器支配
再加 LS                              → v0.6 完整
```

组合量：

```text
L_LOC(σ) = max( L0(σ), L_D(σ), L_AV(σ;U-1), L_TH(σ) )
F(σ)     = max over path certificates
f(σ)     = max( C(σ), F(σ) )
REDUCE(σ,U) → (dead | complete | σ')      # 本轮新增
```

`REDUCE` 不改变 `L_LOC/F/f` 的定义；它只把状态换成“在目标 `≤U-1` 下等价、但剩余任务更少”的状态。关闭 `REDUCE/LS` 后恢复 v0.5-lite。

## 1. 问题、符号与复用的旧结论

### 1.1 形式化问题

```text
P | prec | Cmax
```

给定任务集 `V={1,...,n}`、工时 `p_i∈Z_{≥1}`、优先约束 `E⊆V×V`（DAG）、
同构机器数 `m`。调度由开始时间 `s_i` 和机器 `μ_i` 组成，满足：

```text
(i,j) ∈ E  ⇒  s_j ≥ s_i + p_i
μ_i = μ_j  ⇒  [s_i, s_i+p_i) 与 [s_j, s_j+p_j) 不重叠
```

目标 `Cmax=max_i(s_i+p_i)` 最小，最优值记 `OPT`。

### 1.2 符号表（v0.6 新增/重定义）

| 符号 | 含义 |
|---|---|
| `σ=(S,A,c)` | 状态：已调度集、机器可用时间（升序）、完成时间 |
| `R=V\S` | 未调度集 |
| `C(σ)=max_k A_k` | 已提交 makespan |
| `OPT(σ)` | 从 `σ` 出发完成所有剩余任务的最小绝对 makespan |
| `lo_i(σ)` | 动态 head：已调度前驱的完成时间与未调度前驱链的最大值 |
| `q_i(σ)` | 动态 tail：`i` 之后未调度后继的最长路径（不含 `p_i`） |
| `est_i(σ)` | `max(lo_i(σ), min_k A_k)`，`i` 的最早可能开始下界 |
| `slack_i(σ)` | `(U-1) - (est_i+p_i+q_i)` |
| `U` | 当前 incumbent 上界（可行调度） |
| `U_LS` | 关键路径局部搜索返回的可行上界 |
| `REDUCE(σ,U)` | 减治闭包，返回 `dead/complete/open` |
| `REFUTE` | `slack_i<0` 的子树剪枝 |
| `FORCED-SCHED` | `slack_i=0` 且就绪的无分支调度 |
| `MACH-DOM` | 固定开始时间下的机器选择支配 |
| `B_LS` | 局部搜索的 decode 预算 |
| `N_sched` | 一次闭包中强制调度的任务数 |

### 1.3 复用的 v0.5 结论

以下结论直接继承，不再证明：

- **动作覆盖性**：动作 `(i,k)` 在 `t=max(A_k, max_{j∈pred(i)} c_j)` 开始；从根出发的某条动作序列可达到最优调度。
- **CP 初始上界**：按 `q_i` 降序的 CP 表调度给出可行 `U_0`，且 `U_0≤(2-1/m)OPT`（Graham）。
- **AVAIL 可采纳**：若 `BP(X_W,caps(W,σ))` 不可行，则不存在 makespan `≤H` 的完成。
- **路径下界可采纳**：任意祖先的绝对下界对后代有效；`F` 一致，`f` 沿边单调。
- **Focal 精确**：guide 只排序、不剪枝；只要剪枝用可采纳的 `f`，精确性不变。
- **DOM-GEN 保序**：同 `S` 下 `sort(A_σ)≤sort(A_τ)` 且 `c_σ≤c_τ` ⇒ `OPT(σ)≤OPT(τ)`。
- **证明树规则**：`TERMINAL/PRUNED/EXACT/EXHAUSTED/PACK-CORE-AVAIL` 的局部检查可靠。

v0.6 只替换/扩展搜索树的**展开粒度**和**减治规则**；主循环的 A* 一致性、focal、AVAIL、DOM-GEN 保持不变。

## 2. 动机：v0.5 的三个结构性缺口

### 2.1 缺口一：搜索树的粒度没有减治

v0.5 的减治都在证书层：THRESH 一张证书覆盖 `H≤H*`，INHERIT 一个下界覆盖整棵子树，DOM-GEN 一个状态覆盖被支配状态。但**搜索树本身仍是“每个节点枚举一个 `(i,k)`”**。即使 `slack_i=0` 已经说明 `i` 必须在 `est_i` 开始，v0.5 仍会把 `i` 的调度当作一个分支枚举；如果有多台机器在 `est_i` 可用，还会枚举所有机器。

这带来两个后果：

- 分支因子固定为 `|R|·m`，与 `U` 的紧度无关；
- 当 `U=OPT` 时，大量任务被时间窗强制，但搜索仍然按普通动作展开，浪费节点。

### 2.2 缺口二：focal 只改顺序，不改宽度

v0.5 的 focal 在 `f` 的容许带内按贪心 guide 选点。它让搜索更早找到好上界，但不减少树的分支因子。实验也显示：focal 的收益主要在 anytime（25 次扩展内找到 OPT 的实例数从 11/30 提高到 29/30），而最终节点数的收益部分来自 DOM 和继承。

### 2.3 缺口三：贪心 guide 没有改进

v0.5 的 guide 是 CP/LPT/MWKR 三条表调度规则的构造解，没有在构造解上做局部改进。构造解通常比 OPT 差 1–10；这些差距直接变成 `slack`，削弱 REFUTE/FORCED 的触发。

### 2.4 三个灵感词的分工

- **减治**：REFUTE 减子树、FORCED-SCHED 减任务、MACH-DOM 减分支；三者都以“目标 `makespan≤U-1`”为前提。
- **Local search**：关键路径上的交换/插入改进 `U`；LS 只提供可行上界和关键块。
- **Novel algorithm**：不是新的启发式，而是把“减治闭包”嵌入 A*：搜索节点先被 `REDUCE` 压成强制前缀，再展开少量真正分支。

## 3. 减治层

### 3.1 动态 head/tail 与 est

对当前状态 `σ=(S,A,c)`，按拓扑序计算

```text
lo_i = max( max_{j∈pred(i)∩S} c_j,
            max_{j∈pred(i)∩R} (lo_j + p_j) )
q_i  = max_{j∈succ(i)∩R} (p_j + q_j)
est_i = max(lo_i, min_k A_k)
```

`lo_i` 是 `i` 的最早开始下界：已调度前驱已经完成，未调度前驱至少要 `lo_j+p_j`。`q_i` 是 `i` 之后未调度后继的最长路径。`est_i` 是 `i` 的最早可能开始下界：至少所有前驱完成，且至少有一台机器可用。

**引理 1（est 是下界）**：在任何从 `σ` 出发的合法完成中，`s_i ≥ est_i`。

**证明**：`s_i ≥ lo_i`（前驱约束的最长路径下界），且 `s_i ≥ A_k ≥ min_k A_k`（机器可用时间）。取 max。证毕。

注意：`est_i` 不一定可达；它只是一个下界。这一点对 REFUTE 足够；对 FORCED 我们额外要求 `i` 就绪，此时 `est_i` 可达。

### 3.2 REFUTE：减去子树

定义

```text
slack_i(σ) = (U-1) - (est_i + p_i + q_i).
```

**引理 2（REFUTE 可采纳）**：若存在 `i∈R` 使 `slack_i<0`，则不存在从 `σ` 出发、makespan `≤U-1` 的完成。

**证明**：任意完成的 makespan ≥ `s_i+p_i+q_i`（`q_i` 是 `i` 之后的最长未调度路径）。由引理 1，`s_i≥est_i`，所以

```text
makespan ≥ est_i + p_i + q_i > U-1.
```

证毕。

**搜索规则**：在展开 `σ` 之前，先对所有剩余任务检查 `slack_i<0`。若存在，直接剪掉 `σ` 的整个子树，并在证明 DAG 中记录 `REFUTE(i,U)`。这不需要枚举任何子节点，也不需要装箱测试。

**与 v0.5 AVAIL 的区别**：

- AVAIL 在窗口层检查“强制集能否装入机器容量”，成本 `O(T_BP)`；
- REFUTE 在任务层检查“单个任务的 head+body+tail 是否超过截止期”，成本 `O(n+|E|)`；
- 两者独立，可以叠加。REFUTE 更便宜，且能捕获“优先约束导致的单任务超期”；AVAIL 能捕获“多个任务竞争容量”。

### 3.3 MACH-DOM：减去兄弟分支

设任务 `i` 在时刻 `t` 开始，`t=max(lo_i,A_k)`。若有多台机器满足 `A_k≤t`，它们的开始时间都是 `t`（当 `lo_i≥A_k`）或由 `lo_i` 决定。

**引理 3（机器支配）**：固定任务 `i` 和开始时间 `t`，若 `A_{k1}≤A_{k2}≤t`，则在 `k2` 上调度 `i` 得到的状态 `σ2` 支配在 `k1` 上调度得到的状态 `σ1`：

```text
sort(A_{σ2}) ≤ sort(A_{σ1})   逐分量，
c_{σ2} = c_{σ1}.
```

**证明**：调度后，`σ1` 把 `A_{k1}` 替换为 `t+p_i`，`σ2` 把 `A_{k2}` 替换为 `t+p_i`；其他分量不变。因为 `A_{k1}≤A_{k2}`，`σ2` 保留了较大的旧值、替换了较大的位置，排序后逐分量不大于 `σ1`。`i` 的完成时间都是 `t+p_i`，其他 `c` 不变。由 DOM-GEN，`OPT(σ2)≤OPT(σ1)`。证毕。

**搜索规则**：

- 普通子节点生成时，对每个任务 `i` 按开始时间 `t` 分组；同一 `t` 只保留 `A_k` 最大的机器，其余记录 `MACH-DOMINATED-BY(k*)`。
- 强制闭包中，可行机器集合是 `{k:A_k≤est_i}`；选择 `A_k` 最大者。若有多台并列，任选一台（状态排序后等价）。

**注意**：MACH-DOM 只对“同一开始时间”的机器选择成立。若 `A_k>lo_i`，开始时间 `max(lo_i,A_k)` 随 `k` 变化，不能直接用本引理；这类机器仍保留为独立分支（或在 REFUTE 中处理）。

### 3.4 FORCED-SCHED：减去任务

**引理 4（强制任务）**：若 `i` 就绪（所有前驱已调度）且 `slack_i=0`，则任何从 `σ` 出发、makespan `≤U-1` 的完成都必须让 `i` 在 `est_i` 开始；若有多台机器在 `est_i` 可用，MACH-DOM 选择的机器不劣。

**证明**：由引理 1，`s_i≥est_i`。若 `s_i>est_i`，则

```text
makespan ≥ s_i+p_i+q_i ≥ est_i+1+p_i+q_i = U,
```

与 `≤U-1` 矛盾。所以 `s_i=est_i`。机器选择由引理 3 唯一化（在支配意义下）。证毕。

**搜索规则**：在 `REDUCE` 中，找到就绪且 `slack=0` 的任务 `i`，用 MACH-DOM 选机器 `k`，在 `est_i` 调度 `i`，更新 `S,A,c`，重复。每步减少一个剩余任务，最多 `n` 步。

### 3.5 强制闭包 `REDUCE`

```text
REDUCE(σ,U):
1  S←S_σ; A←A_σ; c←c_σ; count←0
2  loop:
3      if S=V: return (complete, S,A,c,count)
4      计算 lo,q
5      for i∈V\S:
6          est_i←max(lo_i,min_k A_k)
7          slack_i←(U-1)-(est_i+p_i+q_i)
8          if slack_i<0: return (dead, S,A,c,count)
9      forced←{i∈V\S : i 就绪 且 slack_i=0}
10     if forced=∅: return (open, S,A,c,count)
11     选 i∈forced（优先 est 最小；tie 按任务索引）
12     cand←{k : A_k≤est_i}
13     if cand=∅: return (dead, ...)          # 理论不会发生，保守处理
14     k←argmax_{k∈cand} A_k                   # MACH-DOM
15     t←max(lo_i,A_k)                         # 对就绪任务，t=est_i
16     A_k←t+p_i; c_i←t+p_i; S←S∪{i}; count←count+1
```

**引理 5（闭包安全）**：`REDUCE(σ,U)` 返回的 `dead` 意味着 `OPT(σ)≥U`；返回的 `complete` 状态对应一条合法完成，其 makespan `C'` 满足 `OPT(σ)≤C'`；返回的 `open` 状态 `σ'` 与 `σ` 在“是否存在 `makespan≤U-1` 的完成”上等价。

**证明**：归纳每次循环。`slack<0` 由引理 2 排除整个状态；`slack=0` 由引理 4 强制调度，不改变可行解集合（在目标 `≤U-1` 下）；每次调度合法（就绪、机器可用、开始时间不早于前驱和机器）。终止时三种返回值分别对应上述结论。证毕。

**关于多个强制任务的顺序**：若多个就绪任务同时 `slack=0`，它们都必须各自在 `est` 开始。若它们争用同一台机器，先调度一个会使后一个的 `est` 变大，从而 `slack<0`，闭包返回 `dead`——这是正确的（无优于 `U` 的完成）。若它们不冲突，顺序不影响最终状态（在排序 `A` 的意义下）。因此任选顺序安全。

### 3.6 为什么不做链压缩/任务合并

一个自然的减治想法是：若 `i→j` 是唯一前驱/后继，是否能把 `i,j` 合并成一个任务？**不行**。合并会强制 `j` 紧接 `i` 开始，禁止其他任务插入两者之间的机器空闲；这可能改变最优值。对于 `P|prec|Cmax`，链上的任务必须串行，但其他任务可以利用链任务之间的空隙。因此本轮只做“时间窗强制”，不做“任务合并”。

类似地，不能把一条链压缩成一个“超级任务”而不丢失插入机会。REFUTE/FORCED-SCHED 是更保守、可证明的减治。

## 4. 局部搜索层

### 4.1 解的表示与 decode

局部搜索的解用**每台机器的任务序列** `seqs=(seq_1,...,seq_m)` 表示。给定 `seqs`，`decode` 构造图：

```text
优先边：i→j，若 j∈succ(i)（直接边）
机器边：a→b，若 a 紧接 b 在同一 seq_k 中
```

若图有环，`seqs` 不可行；否则按拓扑序计算

```text
start_u = max( max_{v∈pred(u)} finish_v, 0 )
finish_u = start_u + p_u
```

返回 `makespan=max_u finish_u` 和 `finish`。

### 4.2 关键路径邻域

从 `makespan` 最大的任务开始回溯：每一步找前驱或同机器前一个任务中 `finish` 等于 `start_u` 的任务，直到 `start=0`。得到关键任务集合 `Crit`。

邻域：

- **N1（同机器相邻交换）**：对每台机器的相邻任务 `(a,b)`，若 `a` 不是 `b` 的祖先（传递闭包），交换它们。
- **N2（关键任务跨机器插入）**：对每个 `i∈Crit`，把它从原机器移除，插入另一台机器的每个位置（包括首尾）。

每个邻居都用 `decode` 检查可行性和 makespan；只接受 makespan 严格下降的邻居（首次改进）。预算 `B_LS` 次 decode。

**引理 6（LS 可行）**：`LS-CRIT` 返回的 `U_LS` 来自 `decode` 成功且 makespan 严格下降的邻居；因此它是一条合法调度，`U_LS≥OPT`，且 `U_LS≤U_0`。

**证明**：`decode` 检查优先边和机器边无环，按拓扑序计算的开始时间满足所有约束；机器序列保证不重叠。只接受严格下降，且初始解是贪心可行解。证毕。

### 4.3 LS 的定位：只做上界

`U_LS` 是上界，不是下界。即使 LS 陷入局部最优，也不能推出 `OPT=U_LS`。因此：

```text
U_LS 用于更新 U、选择 focal guide、触发 REFUTE/FORCED；
U_LS 不用于剪枝，不进入证明 DAG 的下界证书。
```

LS 的关键路径还可以用来选择 THRESH 的候选窗口（v0.5 的窗口族是 `O(n²)`，关键块可以缩小扫描范围）；本轮未实现该优化。

## 5. 主循环 X-DUB/DC-LS

```text
算法 X-DUB/DC-LS(G,p,m,B)
────────────────────────────────────────────────
1  (lo,q,L0) ← PRECOMPUTE(G,p,m)
2  π0,U0 ← BEST-GREEDY(G,p,m)          # CP/LPT/MWKR 取最优
3  best ← (U0,π0);  U ← U0
4  if LS:  U ← min(U, LS-CRIT(π0))      # 只改上界
5  root ← NEW-NODE(σ0=(∅,0^m,⊥))
6  root.L ← L_LOC(root,U)
7  root.F ← root.L;  root.f ← max(C(root),root.F)
8  Open ← {root};  DomTable ← {(S=∅): [(sort(A),c,root.id)]}
9  F_global ← -∞;  t ← 0
10 while Open ≠ ∅ and t < B:
11     purge Open 中 f≥U 的节点
12     if Open=∅: break
13     f_min ← min_{v∈Open} f(v)
14     if f_min≥U: break
15     v ← FOCAL-SELECT(Open,f_min,ω,B_focal)   # v0.5 不变
16     if DOMINATED(v):
17         U ← min(U,GUIDE(v)); record DOMINATED-BY(witness); continue
18     # ---- 本轮新增：减治闭包 ----
19     status,S',A',c',count ← REDUCE(v,U)
20     if status=dead:
21         record REFUTE/FORCED witness; continue
22     if status=complete:
23         U ← min(U,max(A'));  continue
24     if (S',A',c') ≠ (v.S,v.A,v.c):
25         v ← REBUILD-NODE(S',A',c',F=max(v.F,L_LOC(v',U)))
26         if v.f≥U: continue
27     # ---- 展开 ----
28     t ← t+1
29     U ← min(U,GUIDE(v))
30     for each child w of v:
31         if w complete: U ← min(U,C(w)); continue
32         L_w ← L_LOC(w,U)
33         F_w ← max(v.F,L_w);  f_w ← max(C(w),F_w)
34         if f_w≥U: prune; continue
35         if MACH-DOM(w): record MACH-DOMINATED-BY; continue
36         if DOMINATED(w): record DOMINATED-BY; continue
37         insert w into Open; update DomTable
38     if t mod T_scan = 0:
39         L_root ← THRESH(root,U)
40         F_global ← max(F_global,L_root)
41         for v∈Open: F(v)←max(F(v),F_global); f(v)←max(C(v),F(v))
42     L ← max(L_ROOT_GLOBAL, min_{v∈Open} f(v))
43 end while
44 if Open=∅ or L≥U:
45     PROOF ← BUILD-PROOF-DAG(root,U)
46 return best,L,U,gap=(U-L)/max(1,L),PROOF
```

**与 v0.5 的差异**：

- 第 19–26 行：展开前先做 `REDUCE`；这是本轮的核心。
- 第 35 行：子节点生成时应用 MACH-DOM。
- 第 4 行：根节点 LS 改进 `U`。
- `L_LOC`、`F`、`f`、focal、DOM-GEN、THRESH、证明 DAG 均保持 v0.5 语义。

**注意**：`REDUCE` 返回的 `complete` 状态可能给出 `C'≥U`；此时不更新 `U`（`min` 自动处理），并剪掉该分支。若 `C'<U`，更新 `U`。

## 6. 证明 DAG 与 checker

### 6.1 新增节点类型

在 v0.5 的节点类型上新增：

```text
REFUTE(i, U)                     # slack_i<0
FORCED(i, t, k, U)               # slack_i=0，t=est_i，k 由 MACH-DOM 选
MACH-DOMINATED-BY(i, t, k*, k)   # k 分支被 k* 支配
LS-INCUMBENT(π_LS)               # LS 可行调度
```

### 6.2 checker 规则

```text
CHECK-NODE(v):
1  if v in memo: return memo[v]
2  case v.type:
3    TERMINAL:
4        验证 v 附带完整调度；所有任务恰好一次；前驱/机器约束成立；
5        Cmax(v) ≥ U
6    PRUNED-DUAL:
7        验证 v 的对偶证书 g_H(σ,λ)>0
8    PACK-CORE-AVAIL:
9        按 v0.5 规则验证 (H,a,b,X,π)
10   THRESH-CORE(H*,a,b,X,π):
11        按 v0.5 规则验证
12   REFUTE(i,U):
13        从 σ_v 和原 DAG 重算 lo_i,q_i,A
14        验证 i∈R(σ_v)
15        验证 est_i = max(lo_i,min_k A_k)
16        验证 est_i+p_i+q_i ≥ U
17        验证 U 有可行 incumbent 证书
18   FORCED(i,t,k,U):
19        从 σ_v 和原 DAG 重算 lo_i,q_i,A
20        验证 i∈R(σ_v) 且 i 就绪
21        验证 t = est_i
22        验证 t+p_i+q_i = U-1
23        验证 A_k ≤ t
24        验证 k = argmax_{k'≤t} A_{k'}（或与并列机器等价）
25        验证调度 i 后的状态合法
26   MACH-DOMINATED-BY(i,t,k*,k):
27        验证 A_k ≤ A_{k*} ≤ t
28        验证在 k* 上调度 i 后的 sort(A) ≤ 在 k 上调度 i 后的 sort(A)
29        验证两种调度的 c_i 相同
30   LS-INCUMBENT(π_LS):
31        验证 π_LS 是合法调度；每个任务恰好一次；
32        验证优先约束和机器不重叠；
33        验证 Cmax(π_LS)=U_LS
34   INHERIT(parent):
35        验证 F(v) ≥ F(parent); return CHECK-NODE(parent)
36   DOMINATED-BY(τ):
37        验证 S_v=S_τ; sort(A_τ)≤sort(A_v); c_τ≤c_v
38        验证 CHECK-NODE(τ)
39   EXACT/EXHAUSTED:
40        按 v0.5 规则递归检查所有动作/子节点
41   else: reject
42   memo[v] ← true; return true
```

**DAG 条件**：`FORCED` 产生一条到强制后状态的链接；`MACH-DOMINATED-BY` 和 `DOMINATED-BY` 产生到支配者证明的链接；`LS-INCUMBENT` 只提供上界，不产生下界链接。checker 用 `memo` 检测重复，并在进入时维护递归栈，拒绝环。

### 6.3 可靠性

**定理 4（证明 DAG 可靠；设计，未实现）**：若 `CHECK(root)` 通过，则 `U=OPT`。

**证明**：对 DAG 做拓扑归纳。

- `REFUTE`：引理 2 给出 `OPT(σ_v)≥U`；该节点没有 `≤U-1` 的完成。
- `FORCED`：引理 4 给出任何 `≤U-1` 的完成都包含该调度；子证明覆盖强制后的状态。
- `MACH-DOMINATED-BY`：引理 3 给出 `OPT(σ*)≤OPT(σ_k)`；`k` 分支被 `k*` 覆盖。
- `LS-INCUMBENT`：引理 6 给出 `U_LS` 可行，故 `OPT≤U_LS`。
- `INHERIT/DOMINATED-BY/THRESH-CORE/PACK-CORE-AVAIL/EXACT/EXHAUSTED`：v0.5 的可靠性。
- 结合 `U` 可行，得 `U=OPT`。证毕。

### 6.4 独立性

- `lo/q/A` 由 checker 从 `σ` 和原 DAG 重新计算，不信任搜索器缓存；
- `REFUTE` 的 `est_i+p_i+q_i≥U` 可由 checker 独立重算；
- `FORCED` 的就绪性、开始时间、机器选择逐项验证；
- `MACH-DOMINATED-BY` 的排序向量不等式逐分量验证；
- `LS-INCUMBENT` 的调度可行性独立验证；
- focal、guide、LS 的邻域选择、强制闭包的顺序都不在证明 DAG 里。

### 定理 1（减治等价）

对任意状态 `σ` 和 incumbent `U`，`REDUCE(σ,U)` 的返回值满足：

```text
dead     ⇒ 不存在从 σ 出发、makespan≤U-1 的完成；
open σ'  ⇒ (∃ ≤U-1 的完成从 σ 出发) ⇔ (∃ ≤U-1 的完成从 σ' 出发)；
complete ⇒ 得到一条合法完成，其 makespan 是 OPT(σ) 的上界。
```

**证明**：引理 2/4/5。证毕。

### 定理 2（主算法精确）

若 `X-DUB/DC-LS` 因 `Open=∅` 或 `L≥U` 终止，则 `U=OPT`。

**证明**：由 v0.5 的前沿覆盖性和定理 1，减治不丢失任何优于 `U` 的完成。若存在 `Cmax<U` 的完成，它必须经过某个开节点或某个被减治的状态；减治保持可行性等价，因此它对应一个开节点 `v` 且 `f(v)≤Cmax<U`。这与 `Open=∅` 或 `min f≥U` 矛盾。结合 `U` 可行，得 `U=OPT`。证毕。

### 定理 3（与 v0.5 的兼容）

关闭 `REFUTE/FORCED/MACH-DOM/LS` 后，`X-DUB/DC-LS` 的搜索语义与 v0.5-lite 相同；关闭 `THRESH/INHERIT/DOM/FOCAL` 后，进一步退回 v0.4 的 best-first 语义。

**证明**：这些开关只删除第 19–26、35 行的规则和第 4 行的 LS；其余主循环与 v0.5 相同。证毕。

### 定理 4（证明 DAG 可靠）

设计，未实现；证明见 §6.3。

### 定理 5（任意时刻区间）

在运行任意时刻，`L≤OPT≤U`。

**证明**：`U` 来自 CP/贪心/LS/强制闭包的合法调度，故 `OPT≤U`。`L` 是根证书、`L0` 和前沿 `min f` 的最大值；由 v0.5 的引理 1/2 和定理 1，前沿覆盖且 `f≤OPT`。证毕。

### 定理 6（有限完备性）

搜索树有限；每次展开前进一个任务；REFUTE 只删除无 `≤U-1` 完成的状态；FORCED 每次减少一个剩余任务；MACH-DOM 只删除被支配的兄弟分支。预算无限时，前沿最终为空或 `f_min≥U`。最坏时间复杂度仍指数；这是 NP-hard 问题的预期行为。

## 8. 复杂度分析

### 8.1 单次操作

- **预处理**：拓扑排序 + head/tail，`O(n+|E|)`。
- **`L0`**：`O(n+|E|)`。
- **AVAIL 窗口**：`O(n³)` 朴素（`O(n²)` 窗口 × `O(n)` 强制集），可用二维前缀/排序降到 `O(n²)`；记 `T_win(n)`。
- **REFUTE**：`O(n+|E|)` 计算 `lo/q` 后逐任务检查，`O(n)`。
- **FORCED-SCHED**：每次调度重新计算 `lo/q`，最多 `n` 次，`O(n(n+|E|))`。
- **MACH-DOM**：子节点生成 `O(n·m)`；排序 `A` 的代价 `O(m log m)`。
- **LS**：邻域生成 `O(n²)`；每次 decode `O(n+|E|)`；预算 `B_LS`，总计 `O(B_LS(n+|E|)+n²)`。
- **focal 选择**：扫描 `Open` 为 `O(|Open|)`；guide 计算最多 `B_focal` 次。
- **证明 DAG 检查**：`O(N_proof+|E_proof|)`。

### 8.2 总复杂度

设 `N` 为物化节点数、`B` 为预算：

```text
时间: O( N·(T_win + T_AVAIL + n(n+|E|) + m log m)
        + B·T_G·B_focal
        + B_LS(n+|E|)
        + N_proof )
空间: O( N(n+m) + N_proof )
```

最坏情况：

```text
N = O((m·n)^n)
```

- v0.6 没有改变最坏复杂度；它是“更小的分支因子 + 更强的剪枝 + 更好的上界”，不是新的多项式算法。
- `FORCED-SCHED` 的 `O(n(n+|E|))` 是主要常数开销；在 `n≤15` 时可接受，`n` 很大时需要增量 head/tail 或只对就绪任务做局部更新。
- `LS` 的 `B_LS` 控制成本；本轮 `B_LS=300`。
- `MACH-DOM` 几乎免费，但收益不稳定。

### 8.3 成本控制

- `REDUCE` 只在展开前运行；每个状态最多 `n` 次强制调度。
- `REFUTE` 是 `REDUCE` 的第一次扫描，即使没有强制任务也会执行。
- `LS` 只在根节点/周期性运行；本轮实验只在根节点运行。
- `MACH-DOM` 在子节点生成时应用，不需要额外数据结构。
- 证明 DAG 只在终止时构造，checker 与搜索器隔离。

## 9. 实验设计与结果

### 9.1 设置

- **随机 DAG**：任务按索引拓扑排序；`i<j` 以概率 `ep` 加边；`p_i` 均匀取 `1..pmax`。
- **实例筛选**：先计算根 `L0` 和贪心 `U0`，保留 `U0-L0≥2` 或 base 扩展数较大的实例；避免全部是“贪心即最优”的平凡实例。
- **Small 集**：43 个 `n=9–11`、`m=2–3` 的实例；每个实例用**独立 DFS**（无 AVAIL/FORCED/MACH-DOM/LS/focal，只有 `L0` 下界、状态去重、`U` 剪枝）求 OPT；43/43 对拍一致。
- **Big 集**：12 个 `n=12–14`、`m=2` 的实例；`base` 搜索闭合后的 `U` 作为参考（未独立 DFS）；所有变体闭合且 `U` 一致。
- **base（v0.5-lite）**：`L0 + AVAIL(H=U-1) + INHERIT + focal(ω=2,B_focal=8) + 完全状态去重(S,sort(A),c)`；**不含** THRESH、Pareto DOM、对偶。这是为了隔离本轮变量。
- **AVAIL 实现**：简化窗口 `a∈{0}∪{lo_i}`，`b=H`；不是 v0.5 的完整事件窗口族。
- **LS**：`B_LS=300`；初始解取 CP/LPT/MWKR 中最优；邻域 N1+N2；首次改进。
- **时间**：纯 Python，单线程，单次测量；只用于相对 sanity check，不是 benchmark。

### 9.2 节点数与正确性

**表 1：43 个 Small 实例（DFS 对拍）**

| 变体 | 总扩展 | 平均 | 相对 base | W/T/L vs base |
|---|---:|---:|---:|---:|
| base | 12,351 | 287.2 | 100% | — |
| REFUTE | 3,607 | 83.9 | 29.2% | 19/24/0 |
| REFUTE+SCHED | 3,246 | 75.5 | 26.3% | 22/21/0 |
| MACH | 11,381 | 264.7 | 92.1% | 22/21/0 |
| LS | 11,911 | 277.0 | 96.4% | 12/31/0 |
| MACH+REFUTE | 3,216 | 74.8 | 26.0% | 25/18/0 |
| MACH+FORCED | 2,890 | 67.2 | 23.4% | 26/17/0 |
| **MACH+FORCED+LS** | **2,581** | **60.0** | **20.9%** | **27/16/0** |

- 所有变体 43/43 与独立 DFS 的 OPT 一致；没有出现 `U<OPT` 或未闭合。
- `REFUTE` 单独减少 70.8%；这是本轮最大的单项贡献。
- `SCHED` 在 `REFUTE` 之上再减少 10.0%（3,607→3,246）。
- `MACH` 单独减少 7.9%，在 `FORCED` 之上再减少 11.0%。
- `LS` 单独只减少 3.6%，但在 `MACH+FORCED` 之上再减少 10.7%。
- `REFUTE` 的 `refute_only` 状态总数 3,565；强制调度任务总数 278；触发强制调度的实例 12/43。

**表 2：12 个 Big 实例（base 闭合参考）**

| 变体 | 总扩展 | 平均 | 相对 base | W/T/L vs base |
|---|---:|---:|---:|---:|
| base | 4,714 | 392.8 | 100% | — |
| REFUTE | 3,213 | 267.8 | 68.2% | 7/5/0 |
| REFUTE+SCHED | 2,233 | 186.1 | 47.4% | 7/5/0 |
| MACH | 4,150 | 345.8 | 88.0% | 5/6/1 |
| LS | 3,857 | 321.4 | 81.8% | 6/6/0 |
| MACH+REFUTE | 2,630 | 219.2 | 55.8% | 7/4/1 |
| MACH+FORCED | 2,179 | 181.6 | 46.2% | 7/4/1 |
| **MACH+FORCED+LS** | **1,591** | **132.6** | **33.8%** | **10/2/0** |

- 12/12 所有变体闭合且 `U` 一致；未独立 DFS，不能作为严格最优性对拍。
- `REFUTE` 单独减少 31.8%；`SCHED` 在 `REFUTE` 之上再减少 30.5%（3,213→2,233）。
- `MACH` 单独减少 12.0%，但在 `FORCED` 之上只有 2.4%；有 1 个实例变差（seed 2：27→38）。
- `LS` 单独减少 18.2%，在 `MACH+FORCED` 之上再减少 27.0%（2,179→1,591）。

### 9.3 消融：REFUTE vs SCHED vs MACH vs LS

**表 3：机制分解（总扩展）**

| 变体 | Small 43 | Big 12 |
|---|---:|---:|
| base | 12,351 | 4,714 |
| REFUTE | 3,607 | 3,213 |
| REFUTE+SCHED | 3,246 | 2,233 |
| MACH+REFUTE | 3,216 | 2,630 |
| MACH+FORCED | 2,890 | 2,179 |
| MACH+FORCED+LS | 2,581 | 1,591 |

**解读**：

- **REFUTE 是主要收益来源**：它把“整个状态的子树”减去，而不是只减去一个任务。它的成本只有一次 `lo/q` 扫描。
- **SCHED 的额外收益在 Big 集更大**（30.5% vs 10.0%）：较大的实例更容易出现 `slack=0` 的强制任务。
- **MACH 的收益不稳定**：在 `REFUTE` 之上，Big 集减少 18.1%；但在 `FORCED` 之上只有 2.4%，且有 1 个实例变差。节点数对搜索顺序敏感，支配剪枝不保证单调减少扩展。
- **LS 的边际收益显著**：在 `MACH+FORCED` 之上，Small 减少 10.7%，Big 减少 27.0%。LS 的价值主要不是单独减少节点，而是把 `U` 压紧后让 REFUTE/SCHED 更早触发。

### 9.4 LS 的 U 改进

| 指标 | Small 43 | Big 12 |
|---|---:|---:|
| `U_LS < U0` 的实例 | 18/43 | 8/12 |
| 平均改进 | 1.047 | 2.167 |
| 最大改进 | 10 | 5 |
| LS 单独扩展减少 | 3.6% | 18.2% |
| LS 在 forced 之上的边际减少 | 10.7% | 27.0% |

典型例子：

- Small seed 33：`U0=90 → U_LS=80`，base 53 → full 39。
- Small seed 58：`U0=118 → U_LS=114`，base 210 → full 54。
- Small seed 123：`U0=46 → U_LS=43`，base 205 → full 41。
- Big seed 6：`U0=61 → U_LS=59`，base 76 → full 43。
- Big seed 19：`U0=71 → U_LS=69`，base 3,329 → full 1,035。

LS 的改进幅度不大（平均 1–2），但足以把一些实例推过 `slack=0` 的门槛，或让根节点直接由 `L0` 闭合。

### 9.5 重尾分析

节点数收益高度重尾：

- Small 集中，seed 95 一个实例的 base 扩展为 8,483（占总 base 的 60%）；`forced` 把它降到 1,093。去掉 seed 95 后：
  ```text
  base 3,868；forced 2,153（−44.3%）；full 1,488（−61.5%）。
  ```
- Big 集中，seed 19 的 base 为 3,329（占 70.6%）；`forced` 降到 1,051，`full` 降到 1,035。去掉 seed 19 后：
  ```text
  base 1,385；forced 1,182（−14.7%）；full 556（−59.9%）。
  ```

**结论**：减治是**条件触发**的，不是普遍加速。它在少数“`U` 接近 OPT、优先约束转化为时间窗冲突”的实例上收益巨大；在多数实例上与 v0.5-lite 打平。Big 集的 full 去头后仍有 59.9% 的减少，说明 LS 的 `U` 改进在中等实例上也有独立价值。

### 9.6 负结果：根强制没有增加

本轮最初假设：LS 把 `U` 压紧后，根节点的 `slack=0` 任务会更多，FORCED-SCHED 会更强。实验**不支持**这个假设：

| 指标 | Small 43 | Big 12 |
|---|---:|---:|
| 根节点 `U0` 下强制任务数（均值） | 0.16 | 0.00 |
| 根节点 `U_LS` 下强制任务数（均值） | 0.02 | 0.17 |
| `U_LS` 使根强制数增加的实例 | 0/43 | 1/12 |

原因：

- 当 LS 的 `U` 降到根 `L0` 时，根节点直接由 `L0`/AVAIL 闭合，不需要强制闭包；
- 当 `U` 仍大于 `L0` 时，根的 `slack` 往往仍 `>0`；
- 强制闭包主要在搜索内部、`U` 已经接近 OPT 时触发。

因此，LS 的收益不是“根层强制更多”，而是“更早的全局剪枝 + 少数实例直接闭合”。这是一个需要修正的直觉。

### 9.7 边界与下一轮协议

**本轮未做**：

- THRESH-CERT 的完整实现与组合（实验中的 base 是 v0.5-lite，不含 THRESH）；
- 完整 DOM-GEN Pareto 表（只做了完全状态去重）；
- 证明 DAG 的实际构造与 checker 对拍；
- PSPLIB/fork-join、`n≥20`、`m>3`；
- anytime 曲线（本轮只看总扩展数）；
- 链式强制传播（未就绪任务的 `slack=0` 向前驱传播）；
- LS 的更强邻域（如关键块交换、多任务插入）。

**下一轮协议**：

- **P1（checker）**：独立实现 `CHECK-NODE`，对 500 个 `n≤9`、`m∈{2,3}` 的实例验证 `REFUTE/FORCED/MACH-DOM/LS-INCUMBENT`，目标零假证书。
- **P2（THRESH 组合）**：把 `REFUTE` 与 `THRESH-CERT` 叠加，测“任务层 + 窗口层”双重剪枝的重叠与增量；特别是在 `U0-L0` 较大的实例上。
- **P3（链式强制）**：若未就绪任务 `i` 的 `slack=0`，尝试把强制传播到它的未调度前驱链；证明传播规则，测额外收益。
- **P4（规模）**：PSPLIB/fork-join，`n=20–50`，`m=2–5`；比较 v0.5、v0.6、v0.6-no-LS 的节点数、wall-clock 和 anytime。
- **P5（收益预测）**：分析“哪些实例会触发 REFUTE/FORCED”；用根 `L0`、`U0-L0`、关键路径长度、反链宽度等廉价特征，尝试预测减治收益，避免在无效实例上支付成本。
- **P6（LS 邻域）**：在 Big 集上比较 N1+N2、关键块交换、随机重启；LS 的成本/收益曲线。

## 10. 已知风险

1. **REFUTE 是主要收益，SCHED 叙事被实验降级**：总减少的 70.8%/31.8% 来自 REFUTE；SCHED 只额外贡献 10.0%/30.5%。不能把“无分支调度”当作本轮的主卖点。

2. **收益高度重尾**：少数实例贡献大部分节点减少；平均值会误导。必须报告去头后的数字（Small forced −44.3%，Big forced −14.7%）和分布。

3. **`U` 不紧时减治失效**：`slack<0`/`slack=0` 都依赖 `U` 接近 OPT；若贪心和 LS 都差很多，REFUTE/FORCED 触发率低。LS 平均只改进 1–2，不能保证把 `U` 推到阈值。

4. **LS 成本**：`O(B_LS(n+|E|))` 在 `n≤14` 便宜，但在大规模/稠密 DAG 上可能比省下的节点更贵；本轮没有 `n≥20` 的 wall-clock 数据。

5. **MACH-DOM 非单调**：Small 22/21/0，但 Big 有 1 个实例变差（27→38）；在 `FORCED` 之上 Big 只减少 2.4%。节点数对搜索顺序敏感，支配剪枝不保证减少扩展。

6. **机器同构依赖**：`sort(A)` 支配只在同构机器上成立；对 unrelated machines、带机器 release time 或非同一速度的实例，引理 3 不成立。必须关闭 MACH-DOM。

7. **强制闭包只处理就绪任务**：未就绪任务的 `slack=0` 不会触发调度；这可能错过链式减治。链式传播留到下一轮，当前是保守设计。

8. **证明 DAG 未实现**：`REFUTE/FORCED/MACH-DOM/LS-INCUMBENT` 的 checker 规则只是设计；未经独立对拍。一个错误的强制方向或机器支配方向会接受假最优。

9. **实验规模小**：43 个 Small + 12 个 Big；没有 PSPLIB；没有 `n≥20`；不能外推到工业规模。Big 集的 `U` 不是独立 DFS 验证的。

10. **base 是 v0.5-lite**：不含 THRESH、Pareto DOM、对偶；本轮增量不能直接等同于“在完整 v0.5 上的增量”。THRESH 可能与 REFUTE 重叠（都捕获截止期/装箱冲突），需要 P2 测量。

11. **没有 anytime 曲线**：本轮只报告总扩展数；v0.5 的 focal 优势主要在 anytime。v0.6 是否改善 anytime 还未测；LS 的 `U` 改进可能对 anytime 有正贡献，但未验证。

12. **LS 邻域有限**：只做关键路径相邻交换和跨机器插入；没有关键块交换、多任务插入、随机重启。LS 的 `U` 改进可能被低估或高估。

13. **时间数据不是 benchmark**：纯 Python 单次测量；没有置信区间；不同变体的 guide 调用次数不同，wall-clock 比较只能作 sanity check。

14. **最坏情况没有改善**：B&B 仍指数；REFUTE/FORCED/MACH-DOM/LS 都是常数或参数化改进。本轮的贡献是“更小的分支因子 + 条件减治”，不是新的最坏情况界。

15. **REFUTE 与优先约束间隙**：REFUTE 只能捕获“单任务 head+body+tail 超期”；如果间隙来自多任务的机器竞争或优先约束的组合，REFUTE 无能为力，需要 AVAIL/THRESH 或更强的全局下界。

---

## 11. 一句话最大风险

**当前方案最大的风险是：减治的收益主要来自任务层 REFUTE 剪枝而非无分支调度，且高度重尾——在少数 `U` 接近 OPT 的困难实例上收益巨大，在多数实例上与 v0.5-lite 打平；一旦 `U` 不紧或优先约束不能转化为时间窗冲突，FORCED-SCHED 与 MACH-DOM 的收益会迅速消失，而 LS 和强制闭包的成本在更大规模上可能反超。**
