## 1. 直觉：两个灵感如何改写本轮

### 灵感 1 ·「需求洞察」→ 榜单是「说出来的需求」，语料增长是「做出来的需求」

需求洞察的第一课是区分三种需求：

- **stated need（说出来的）**：榜单要「平均成功率 + 步骤分」。但它 Coming Soon，信息量为零，且口径冻结——它不告诉你未来要什么。
- **revealed need（做出来的）**：组织方每周往 Dex1 里加什么任务。11-20 加的是折叠衣物、装配凳子；11-12～11-20 加的是串珠、拼图、装配鼠标/表带、分装药片——**全部是长程、多步、灵巧**，不是 32 项里那种单段式桌面操作。这是「用数据投票」。
- **latent need（没说但真正要的）**：他们要的不是某个队伍在 32 项上刷分，而是**一套能随着任务分布扩张而持续变强的配方**——一个可复用的数据/控制/评测飞轮。

**直觉结论**：把 32 项当「目标」是把一个**采样切片**误当成**总体分布**。正确的优化对象是那个正在增长的分布；32 项只配当**回归测试集**。这与第 3 轮「窗口期建护城河」并不矛盾，而是把护城河从「赢固定靶」升级为「随移动靶一起变强」。

### 灵感 2 ·「可扩展性」→ v3 的隐形 O(N) 债

v3 的清单看起来很完备，但把「任务数 N」当成变量重读，会发现大量**隐藏的 per-task 手工胶水（O(N) glue）**：

- IP-13「①任务→场景图 schema（从 IP-06 标注导出）」——每个新任务都要人写 schema；
- IP-09 的 waypoints / 容差——每任务手工标定；
- IP-14 的探测白名单、IP-15 的干扰阈值——按任务/相位手调；
- IP-06 的失败矩阵——每新增任务都要重新铺标注。

任务从 32 → 110 → 更多时，这些胶水**线性增长**，工程成本吃掉全部收益。这就是「手工作坊式完备」，不是「可扩展」。

可扩展性至少分四种，本轮只聚焦后两种（前两种在单 checkpoint API 前提下不是瓶颈）：

1. 模型参数可扩展性（scaling law）——不是本轮重点；
2. 数据规模可扩展性——用 E636 拟合；
3. **工程可扩展性**：新增一个任务的边际工程成本是否 →0；
4. **评测可扩展性**：新增任务能否自动进入代理评测与回归。

**直觉结论**：把 O(N) 的手工胶水，换成「O(1) 编译器 + O(N) 数据」。数据是便宜的（语料已在自动增长），工程是贵的（人力有限）。一个编译器编译所有任务，胜过为每个任务写一遍。

### 灵感 3（综合）·「需求 × 可扩展」= 面向移动目标的规模经济

两条灵感合起来给出一个清晰判据：**唯一耐久的研究资产，是「边际任务成本 → 0 而边际效用 > 0」的那一类**。

- 固定靶（32 项）上的手工优化，边际效用随任务数增加而摊薄、边际成本却线性上升——规模不经济。
- 面向语料 roadmap 的编译器 + 自动数据环，边际成本趋零、边际效用随分布扩张而累积——规模经济。

这把第 3 轮的「状态层」从「为 32 项手写的场景图」重写为「被编译器自动生成的场景图」，是**深化而非推翻**：IP-13 的数学（卡方断言、重定位）不变，变的是 schema 的来源。

## 2. 研究问题（新增 Q13–Q15，接第 1–3 轮 Q1–Q12）

- **Q13（需求信号有效性）**：语料发布节奏是否是评测分布的有效代理？即评测分布 P_e 是否随语料分布 P_d 漂移（漂移参数 ρ>0），还是恒为冻结的 32 项（ρ≈0）？这是本轮整个论点的**可证伪前提**（E637）。
- **Q14（自动 schema 可行性）**：仅凭演示 + 语言，能否为长程灵巧新任务自动编译出与手工相当的场景图 schema 与 waypoints（覆盖率 ≥95%、绑定错误 ≤1%、编译 ≤1 人时/任务）？（E635）
- **Q15（规模指数）**：在增长的 Dex1 语料上，本配方的数据规模指数 λ 是多少？语料调优的 checkpoint 在留出新任务上是否不劣于、且优于冻结 32 项调优的 checkpoint？（E636/E637）

## 3. 设计原则（新增 P13–P14，接第 1–3 轮 P1–P12）

- **P13（无标度优先 / scale-free first）**：任何组件的工程成本若随任务数增长，必须证明其边际效用足以覆盖；优先选 O(1) 不变量，其次「O(1) 编译器生成 O(N) 数据」，最后才允许 O(N) 手工胶水，且必须登记在案（IP-18 审计）。
- **P14（移动靶对齐）**：优化对象是「揭示出的需求分布」（语料 roadmap），冻结的 32 项只作回归测试与合规底线；任何只在 32 项上有效的组件标注为「competition-only」，不得计入护城河。

## 4. 清单处置（深化 / 修剪 / 新增）

- **新增**：IP-16 TaskSchemaCompiler（P0，规模经济基石）、IP-17 CorpusScalingLoop（P1）、IP-18 ScalabilityAudit（P1，度量仪）。
- **深化**：IP-13（schema 来源从手工改为编译器输出）；IP-09（waypoints 改由编译器生成）；IP-06（新增自动任务摄取 + 留出新任务评测）；IP-12（课程按 E638 的边际价值排序，而非均匀铺）；IP-10/IP-14 的探测与负样本统一进 IP-17 的自动数据环。
- **修剪/降级**：把 v3 里所有「按任务手写」的隐性假设显式化为 O(N) 债并列入 IP-18 审计；只在 32 项有效的项标 competition-only，不计入护城河。
- **MVP 不变**：IP-06 + IP-02 + IP-09 + IP-03 + 通用基线。**顺序修正**：IP-16 必须排在「把 IP-13/IP-14 扩到多任务」之前——否则会先背上 O(N) 债再想还，是最差顺序。
- **退化链不变**：Level-0..1.6 沿 v3；编译器失败时，单任务回退到 v3 的手工 schema（编译器是加速器，不是单点故障）。

## 5. 本轮最大风险（一句话）

**「需求信号」只是代理——若评测真就是冻结的 32 项（ρ≈0），或语料增长是探索性噪声而非奖励信号，则整条「面向移动靶的规模经济」押注落空，TaskSchemaCompiler 变成给没人评分的任务造编译器**；对冲是用 E637 尽早做证伪，且编译器与数据环均可在单任务上降级回 v3 手工路径，不绑定。

## 6. 下一轮迭代计划（深化与修剪，不推倒重来）

- **深化**：IP-16 的演示分段与容差自动估计（E635）；IP-18 的 e_c(N) 阶拟合（E634）；E637 作为**最高优先级证伪实验**先跑。
- **修剪预案**：E637 若显示 corpus-tuned ≤ frozen-32（ρ≈0）→ 需求论点证伪，回退 v3 bespoke，仅保留 IP-16 作为提速工具；E635 编译覆盖率 <80% → 编译器降级为「半自动建议 + 人工确认」，仍比全手工便宜；E636 的 λ 置信区间跨 0 → 不据此扩算力。
- **待外部事件**：不变——榜单开放日 48 h 内复核 F1/F2 与任务级口径；规则手册关闭 Q3/Q4/Q9/Q12。新增：若组织方公布新挑战任务集（分布迁移的硬证据），立即触发 E637 重跑。

## 3. 新增 IP 详述

### IP-16 · TaskSchemaCompiler 任务模式编译器（P0，新；规模经济基石）

- **动机**：v3 的 IP-13/IP-09 每个任务都要人写「场景图 schema + waypoint 序列 + 容差 + 探测白名单」。语料已从 32 涨到 110 且在涨（F5），这条路是 O(N) 债：任务越多，工程越慢，收益越摊薄。编译器把「人写」换成「程序从演示推」。
- **与现有方案差异**：不是新模型，是**从演示自动抽取阶段结构**的工程件——夹爪开合事件切分阶段（approach/grasp/transport/place/release），从演示方差估计容差（取代拍脑袋阈值），从语言核验类别与顺序。产出的 schema 直接喂 IP-13，产出的 waypoints 直接喂 IP-09。
- **技术可行性**：中高。分段与容差估计是成熟信号处理；难点在长程灵巧任务（折叠衣物、装配）的阶段语义歧义 → 用语言先验 + 多演示一致性投票消歧；冲突时回退人工确认（半自动仍比全手工便宜）。
- **资源**：演示语料已有（Dex1）；算力=小（离线一次性编译，单卡分钟级/任务）；接口=无新增字段（编译器离线，在线仍是同一 API）。
- **落地步骤**：①夹爪事件分段器；②每阶段锚点对象挖掘（无手工类别表）；③容差从演示方差估计（与 U17 的 Σ 同源，天然自校准）；④语言一致性核验；⑤编译产物 schema→IP-13、waypoints→IP-09；⑥E635 在留出新任务上对标手工。
- **风险**：长程任务分段错误会级联（对策：阶段置信度门限 + 冲突回退人工）；新任务与 32 项域差（对策：留出法评测，绝不在 32 项上调编译器）。

### IP-17 · CorpusScalingLoop 语料规模环（P1，新）

- **动机**：F5 表明语料在自动增长，但 v3 的数据环（IP-10/IP-12/IP-06）假设语料是静态的。需求洞察的落点是：**把「语料增长」变成「配方自动变强」**，而不是等人手动搬运新任务。
- **差异**：一个流水线——新任务出现 → 自动拉取 → 自动阶段标注（复用 IP-16 分段器）→ 按边际价值排序入课程（E638）→ 进代理评测（留出）。与 IP-10 负样本、IP-14 探测统一过 P12 记账。
- **可行性**：中高。全部组件现成；风险在自动标注质量（用 IP-16 的分段置信度做闸门）。
- **资源**：中（数据搬运 + 标注算力）；复用 IP-06/16。
- **步骤**：①语料变更监听（按集合 lastUpdated/子集 lastModified）；②自动拉取与去重；③自动阶段标注（IP-16 分段器）；④边际价值排序（E638）；⑤入课程与留出评测；⑥闭环指标（λ、A）。
- **风险**：自动标注噪声污染课程（对策：置信度闸门 + 小比例人工抽检）；算力随语料膨胀（对策：按 E638 边际价值截断，不平均用力）。

### IP-18 · ScalabilityAudit 可扩展性审计（P1，新；度量仪）

- **动机**：需求洞察要求「知道自己到底在为什么付费」。v3 从没度量过「新增一个任务的边际工程成本」。没有度量，就分不清「资产」与「债」。
- **差异**：纯离线元工具，不改在线策略。对每个组件在 N∈{32,64,110} 上实测工程工时与运行时，拟合阶（O(1)/O(N)/O(N²)），算摊销比 A = 边际效用 / 边际成本。
- **可行性**：高（度量与拟合）。
- **资源**：近零。
- **步骤**：①定义 e_c(N) 采集协议（工时日志 + 运行时埋点）；②阶拟合；③A 计算；④输出审计表并标注 O(N) 债；⑤反馈给 IP-16（优先消除最大 O(N) 项）。
- **风险**：工时度量主观（对策：固定采集协议 + 双人标注一致性）；把 A 当成精确值（对策：只用于排序与阈值，不用于绝对预测）。

## 5. 符号与定义（新增 U19–U21；U1–U18 沿用第 1–3 轮）

- **定义 U19（需求信号）**：`n(t) = (n_k(t))_k`，`n_k` 为任务类别 k 的发布强度（以语料新增子集数/单位时间计）。区分 stated need（榜单口径，冻结）、revealed need（n(t) 的经验分布）、latent need（可复用飞轮）。策略对齐度 `align(s) = cos(v_s, n(t))`，`v_s` 为研究投入向量。
- **定义 U20（任务数可扩展性与摊销比）**：设组件 c 的工程成本为 `e_c(N)`、效用贡献 `u_c(N)`。称 c 为**无标度**若 `e_c = O(1)`；**逐任务**若 `O(N)`；**超线性**若 `O(N²)`。栈的**摊销比** `A = ΔU_new / ΔC_eng`（新增一个任务的边际效用 / 边际工程成本）；可扩展 ⇔ `A ≥ 1` 且 `dA/dN ≥ 0`。
- **定义 U21（任务无关契约）**：scale-free 核心与任务数据之间的接口 `K = (schema, waypoints, tolerances, phase_gates)`，要求**可由演示+语言编译得到**，而非人工编写；编译器 `Compile: (Demos, Language) → K`。IP-13/IP-09 只消费 `K`，不消费任务名。

```python
def compile_task_schema(task_id, demos, language):
    phases = segment_by_gripper_events(demos)          # 夹爪开合切分: approach/grasp/transport/place/release

        schema.append(Waypoint(ph, anchors, tol, gate))
    schema = verify_with_language(schema, language)     # 类别/顺序与指令核验
    return schema                                       # → 喂 IP-13；waypoints → 喂 IP-09
```

```python
def scalability_audit(stack, task_sets):               # task_sets: N=32,64,110
```

## 7. 推导（新增引理 L14–L16；L1–L13 沿用第 1–3 轮）

**引理 L14（摊销交叉点 / 规模经济的门槛）** 设 bespoke 栈 B 成本 `C_B(N)=α+βN`（β>0 为逐任务胶水），可扩展栈 S 成本 `C_S(N)=γ+δN`（δ≈0，但固定投入更高 `γ>α`）。校准使二者在 N0=32 上效用相同。则 S 的单位效用成本在 `N > N* = (γ−α)/(β−δ)` 后严格低于 B，`N*` 即规模经济门槛。**推论**：语料已在 110 且增长（F5），若 `N*<110`，可扩展栈**现在就**占优；若 `N*>110`，则需先降 `γ`（复用现成件）再谈。⇒ 用 IP-18 实测 β、δ、N*，而不是争论「要不要可扩展」。∎

**引理 L15（移动靶对齐的占优与证伪）** 设评测分布 `P_e(t)=(1−ρ)P_0+ρP_d(t)`（P0=冻结 32 项，P_d=语料分布，ρ∈[0,1] 为漂移）。对齐语料训练的策略 `π_d` 与对齐冻结集训练的策略 `π_0` 的期望效用差 `ΔU(ρ) = ρ·[E_{P_d}u(π_d) − E_{P_d}u(π_0)] + (1−ρ)·[E_{P_0}u(π_d) − E_{P_0}u(π_0)]`。若 `π_d` 在 P_d 上不劣于 `π_0` 且两策略在 P_0 上持平，则 `ΔU(ρ)≥0` 且随 ρ 单调增。**关键**：ρ=0（评测真冻结）时 `ΔU=0`——这正是可证伪点（E637）。⇒ 需求论点成立当且仅当 ρ>0；先测 ρ，再投 IP-16。∎

**引理 L16（边际数据价值与课程排序）** 设效用随语料量 `M` 服从 `U(M)=U∞ − k·M^{−λ}`，则边际价值 `dU/dM = kλ·M^{−(λ+1)}` 随 M 递减。故在语料增长时，**应先吃边际价值最高的任务**（高 transfer/step），而非均匀铺。长程灵巧任务（折叠/装配）因覆盖多阶段、多接触，预期早期边际价值高（E638 检验）。⇒ 课程排序器 = 边际价值排序器，与 IP-17 共用。∎
