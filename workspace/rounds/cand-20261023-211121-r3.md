## 0. 本轮思考轨迹（先给结论，再给推理）

本轮仍按「宇树科技 UniBot 世界挑战赛」理解：G1 人形机器人、32 项桌面任务、5 类泛化、通才模型赛道、单模型、自部署 API。搜索到的 Telegram 交易机器人 Unibot、IRC UniBot 与赛题无关，不展开。

我先做了四次核对，避免在旧结论上继续加码：

1. **规则复核**：中文/英文参赛手册 1.1–2.2 仍可读。结论没有变：仅通才模型赛道；**单模型完成全部 32 任务，不得混合多个模型**；每任务 **10 次**，5 类泛化各 **2 次**；单次真机最多 **180 秒**；按 32 任务**总平均成功率**排序，成功率相同才看**总平均步骤分**，再相同看提交日期；模型由选手自部署，平台只远程调用；单任务调试通道不计分。
2. **榜单复核**：首页仍展示 MolmoAct/DexHacker 29.7%、WALLOSS 28.5%、DreamZero 27.9% 等一行表，但整块仍被「即将发布 / Coming Soon」覆盖；`leaderboard.html` 与 `runs.html` 都还是 Coming Soon。**这些分数仍是占位展示，不能当真实排名证据。** 只能拿论文分析架构，不能拿分数反推强弱。
3. **接口复核**：提交 README 比上一轮读得更细。`action.pivot[7]` 是 **shared 必填**，即使选 `ee` 控制也要返回；观测只有 4 路 RGB、双臂关节、EE pose、夹爪、`lower_body[15]` 和一句 `language`；**没有 camera_params、没有 task id、没有深度图**；`action_chunk_size` 在 metadata 里固定；`obs_delta_indices` 同时决定“发哪些观测”和“怎么堆帧”；评测会记录每步延迟、延迟波动和动作统计规律。
4. **数据复核**：32 个 HuggingFace 数据集逐项求和 **33,276 episodes**（官网四舍五入 32k），169h，Apache-2.0；4 路 480×640、30fps、AV1；每任务 `tasks.parquet` 有 **5 条英文复述**；`info.json` 有 2–5 个官方 `score_steps`，合计约 **94 个评分点**；30 个任务有 `human_1/human_4` 备注（T31/T32 为空）。`lower_body[15]` 的名字里包含 `waist_yaw/roll/pitch`，所以腰部在部署时**可观测**；但动作侧只能通过 `action.pivot` 间接控制。

然后我把 2026 年下半年与“推理时验证 / 意图”相关的论文扫了一遍。最重要的变化是：**test-time verification 已经从“可选技巧”变成一条独立路线，而且开始在真机上拿到两位数的提升。**

- **DiVeR**（arXiv:2610.04933，2026-10-04）：decision-critical verifier；真实 π0.5 上 58.3% → 71.9%（+13.6pp），verifier 只加约 1ms。
- **VeriVLA**（arXiv:2610.21985，2026-10-15）：latent world model + adaptive trigger；真实任务 completion 50.8% → 65.5%，每次触发约 326ms。
- **VLA-ATTC**（arXiv:2605.01194，2026-05-02）：uncertainty “cognitive clutch” + relative action critic；LIBERO-LONG 上把 π0.5 的失败率降了 >50%。
- **CheckVLA**（arXiv:2607.26789，2026-07-29）：action-conditioned world model 做执行时验证；RoboCasa365 上 36.1% vs periodic replanning 27.6%（+8.5pp）。
- **RESCUE**（arXiv:2610.13516，2026-10-09）：光有“准确告警”不够，还要看告警是否**来得及救**、以及不必要干预会不会破坏本来成功的执行。

这些结果说明：**在成功率优先的赛制里，推理时算力是一根被低估的杠杆。** 但直接照搬不行，UniBot 有三个硬约束：

- 数据只有成功演示，没有失败 rollout；DiVeR/RoboMonkey 那套 success-vs-failure verifier 没有现成负样本。
- 规则要求单模型；不能在线跑第二个 VLM/verifier/世界模型。
- 单次 180s，且 README 会记录延迟和动作统计；每步 best-of-N 会把延迟和抖动打爆。

第三条刚好和“意图识别”接上。**HINT**（arXiv:2609.02653，2026-09-02）的核心观察是：语义意图只在操作模式转换时稀疏变化，连续控制主要依赖物体-手的关系；应该在模式转换时做一次语义推理，然后保持承诺。**IntentVLA**（arXiv:2605.14712，2026-05-14）进一步指出：相似观测可能对应不同短程意图，逐帧重采样会导致 chunk 间冲突；应该用历史编码一个短程意图表示。**DIAL**（arXiv:2603.29844，2026-03-31）则用 latent intent bottleneck 把 System-2 的意图 foresight 和 System-1 的动作解耦，且仍是单模型。

三者合起来给了一个很具体的设计：

> **意图不要每帧重算；在“子目标完成 / 状态回退 / 人手介入 / 接触前 / 高不确定”这些事件点更新一次，然后保持承诺；只有这些事件点才值得花 best-of-N 的算力。**

这让我把上一轮的 RUBICON 3.0 重新定位。上一轮的三件事仍然对：

- **SPA-VLA** 的部件 token 是“抓哪里/插哪里/进度到哪”的接口；
- **RPSM** 的可逆谓词是“状态回退”的接口；
- **Compliance / Endurance / Portfolio** 是“不归零 / 不超时 / 不浪费预算”的接口。

但它们都还是“能力层”。缺的是**决策治理层**：什么时候信当前意图、什么时候验证、什么时候修复、什么时候放弃成功转 salvage、算力花在哪。

所以本轮升级为 **RUBICON 4.0 = IGX（Intent-Governed eXecution）**：

- **ISM（Intent State Machine）**：用语言 + 历史 + 部件谓词维护一个紧凑的意图状态；只在事件点更新；输出 active subgoal、goal predicates、intervention mode、budget。
- **ICV（Intent-Conditioned Verifier）**：在事件点采样 K 个 action chunk，用**同一 checkpoint** 的 verifier head 按“当前意图下的目标满足概率”排序；负样本用成功演示的 counterfactual 扰动构造，不依赖失败 rollout。
- **IIR（Intervention Intent Recognizer）**：把官方 `human_1/human_4` 从“统一撤销”细分为 undo/relocate/remove/reset/block/assist，分别 repair / re-ground / scan / wait / abort；这是“意图识别”最直接的落点。
- **CBC（Competition Budget Controller）**：在 180s 和 p99 约束下分配验证算力；成功率优先，但在明显失败时切到 salvage 模式最大化步骤分；按任务组合分配调试预算。
- 底座保留 **SPA-VLA + RPSM + Compliance Compiler + Endurance Governor**。

这一轮最重要的“算账”：

- 10 trials/task 中，**人为干扰占 2 次 = 20%**。如果 human trials 的成功率从 20% 提到 50%，总体 **+6pp**；这比在简单任务上抠 1–2pp 划算得多。
- 320 trials 的总体 SE ≈ **2.6pp**；3pp 真实优势只有约 79% 概率排名更高，5pp 才约 91%。所以要押“能上 3–5pp”的杠杆，而不是 1pp 的架构微调。
- 步骤分只在成功率打平时有用；但 2.6pp 的噪声意味着打平并不罕见，所以步骤分是**廉价 hedge**，不是主目标。RGS（rubric-grounded subgoals）用官方 `score_steps` 做辅助监督，既帮成功率（少漏子目标），也帮步骤分。

修剪：

- **不再把 world model 作为独立 P0**；把它降为 ICV 的一个 latent consequence head（同一 checkpoint）。
- **不再把“泛化类型识别”作为主卖点**；它是 P2，因为可能学到评测者的虚假线索，收益/风险不划算。
- **不再为步骤分牺牲成功率**；salvage 只在成功概率很低（例如 <0.1）或剩余时间 <10s 时启用。
- **不再追求从零训练 / 在线 RL / 运行时外部 VLM**；这些都不符合算力、延迟、单模型约束。
- **Waist/pivot 降为接口校准项**：`lower_body` 已含 waist，`action.pivot` 必填；默认静态，只有任务确实需要时小范围动。

一句话押注：

> **把“意图”做成一个事件触发的状态机，用它来调度“同一 checkpoint 内的 counterfactual verifier + 分型干预响应 + 180s 预算”，在人类干扰占 20% 的赛制里把成功率抬 3–5pp。**

### 1.2 接口层的新确认

- **`action.pivot[7]` 是 shared 必填**：即使 `control_space="ee"`，也要返回 `action.left_gripper`、`action.right_gripper`、`action.pivot`。`action.pivot` 的 7 维是 `vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height`。
- **观测里没有 `camera_params`、没有深度、没有 task id**：只有 4 路 RGB、`left_arm/right_arm`、`left/right_ee_pose_gripper_base`、`left/right_gripper`、`lower_body[15]`、`language`。因此 3D 部件定位不能依赖评测时读外参；要用固定名义标定 + 相对几何 + 学习深度/尺度。
- **`lower_body[15] = 双腿 12 + waist yaw/roll/pitch 3`**：腰部可观测；但动作侧没有 `action.waist_action_joint`，只能通过 `action.pivot` 控制。默认静态最安全。
- **`action_chunk_size` 固定**：不能在 episode 中动态改 chunk 长度；best-of-N 只能在“返回哪一个 chunk”上做文章，不能在 chunk 内部暂停。
- **`obs_delta_indices` 决定发哪些观测**：只声明模型真正需要的键，能显著降低网络/序列化延迟；`language` 必须 `[0]`。
- **`image_resize` 在评测端做**：可以用较低分辨率换延迟，但腕部接触细节不能降太多。

### 1.3 数据层的新确认

- 32 个 HF 数据集逐项求和 **33,276 episodes**；官网 32k/169h 是四舍五入。
- 每任务约 970–1,533 episodes；30fps；4 路 RGB；AV1；Apache-2.0。
- `tasks.parquet` 每任务 **5 条英文复述**，用 `@` 分隔；例如 HangCup 的 5 条都表达“挂到杯架标记处”，但措辞不同。
- `info.json` 的 `score_steps` 合计约 **94 个评分点**（2–5 个/任务），是免费的稠密子目标监督。
- 30 个任务有 `human_1/human_4` 备注；T31/T32 为空。备注不是“手挡一下”，而是**语义状态改变**：撤销、移除、重置、移动底座/架子、阻塞。

## 2. 三条灵感词的落点

### 2.1 「意图识别」→ ISM + IIR + RGS

我把“意图”拆成四层，避免一个词包打天下：

1. **任务意图（task intent）**：语言要达成的目标，表示成 goal schema（动词、对象/部件、目标、顺序、约束）。
2. **程序意图（procedural intent）**：当前做到哪个子目标、下一个是什么、哪些已完成/被撤销。用官方 `score_steps` 做弱监督。
3. **干预意图（intervention intent）**：人手在干什么——undo / relocate / remove / reset / block / assist。直接对应官方 `human_1/human_4`。
4. **评测意图（regime intent）**：当前 trial 属于位置/干扰物/背景/未见物品/人为干扰哪一类。P2，先不做主卖点。

其中 2 和 3 是本轮 P0；1 是底座；4 是观察项。

### 2.2 「比赛策略」→ CBC + 两模式执行 + 组合优化

- **成功率优先**：所有决策先最大化 full success；步骤分只在平分时有用。
- **人类 trial 杠杆**：2/10 = 20% 的 trial 是人为干扰；把 human 成功率从 20% 提到 50%，总体 +6pp。这是最便宜的 3–5pp 来源之一。
- **验证算力预算**：best-of-N 不是越多越好；要在 180s 内、在 p99 约束下、在“值得救”的事件点花。
- **两模式执行**：成功概率高时打 success；成功概率很低时切 salvage，最大化步骤分，避免“成功没了、步骤分也没了”。
- **组合优化**：先消灭 0% 任务，再攻人类 trial，再攻接触密集任务；用 Beta-Binomial 和 ROI 分配调试预算。

### 2.3 「UniBot」→ 单模型 / 180s / N 端口 / 5 类泛化

- **单模型**：所有头（part / intent / verifier / action）在同一计算图、同一 checkpoint；运行时不再加载第二个模型。
- **180s**：CBC 控制验证调用次数；长任务优先保成功，短任务可以多验证。
- **N 端口**：共享后端 + 会话隔离；验证算力要能被 token bucket 限制，避免一个端口把 GPU 打满。
- **5 类泛化**：训练/验证按 5 类分层；人类干扰单列；未见物品用部件语义而不是物体 ID。

## 3. 竞争分析与瓶颈

### 3.1 榜单审计

- 首页仍显示 8 行模型/分数（MolmoAct 29.7%、WALLOSS 28.5%、DreamZero 27.9%…），但整块仍被「即将发布 / Coming Soon」覆盖。
- `leaderboard.html` 与 `runs.html` 都是 Coming Soon；没有真实提交记录。
- 因此：**不能引用“榜首 <30%”作为真实证据**；只能把它当“难度直觉”。真实排名不可见，强基线只能从论文/模型卡分析。

### 3.2 真实强基线的共同短板

| 模型/路线 | 强项 | 在本赛的短板 |
|---|---|---|
| WALL-OSS-0.5 / π0.5 / GigaBrain | 通用 VLA、数据规模、语义泛化 | 接触最后几毫米；无显式可逆状态；无预算感知 |
| MolmoAct2 | 开放动作推理、空间推理 | 推理链延迟；接触精度；单模型集成复杂 |
| DreamZero | world model、物理动态、跨 embodiment | 14B 算力/延迟；长程状态验证弱 |
| DiVeR / VeriVLA / VLA-ATTC | 推理时验证、best-of-N | 需要失败数据或独立 verifier；未针对 180s/单模型/人类干扰 |
| HINT / IntentVLA / DIAL | 意图状态、模式转换、latent bottleneck | 没有和 verifier/预算/干预响应结合 |

**共同瓶颈**不是“模型不够大”，而是：

1. **接触最后几毫米**：插头 prong、网线水晶头、钥匙、瓶盖、拉链、试管。
2. **可逆状态**：官方 human 干扰会撤销已完成子目标；单调进度头会继续往前走。
3. **长程状态**：4–5 检查点任务容易漏点、premature stop、失败不重试。
4. **决策治理**：什么时候验证、什么时候修复、什么时候放弃、算力花在哪。
5. **部署稳定性**：4 路视频、N 端口、长时并发；p99 抖动会直接吃掉成功率。

### 3.3 本轮的空白点

把 2026 年的论文放在一起看，会发现一个明显的空白：

> **没有一篇工作同时解决“只有成功数据 + 单模型 + 180s 预算 + 语义人机干扰”这四个约束。**

- DiVeR/RoboMonkey：需要 success/failure rollout 训练 verifier。
- VeriVLA/CheckVLA：需要单独训练/冻结的 world model，单模型合规有风险。
- VLA-ATTC：relative critic 很好，但没有意图状态和干预分型。
- CoVer-VLA：需要运行时 VLM 生成复述，延迟/规则风险。
- HINT/IntentVLA/DIAL：有意图，但没有 verifier/预算/修复。

这就是 IGX 的位置：**把意图、验证、预算、干预响应做成一个单 checkpoint 的决策治理层。**

## 4. 创新点排序（本轮）

| 顺序 | 创新点 | 价值 | 风险 | 依赖 |
|---|---|---|---|---|
| P0 | **IGX 总架构**：事件触发意图 + 同 checkpoint 验证 + 预算控制 | 高 | 中 | SPA-VLA + RPSM |
| P0 | **ICV + CFV**：意图条件 verifier + 无失败数据的 counterfactual 负样本 | 高 | 中高 | action-expert 特征 + 硬负样本 |
| P0 | **IIR**：干预意图分型 + 分型响应 | 高（人类 trial 20%） | 中 | RPSM + 合成/真机干预数据 |
| P0 | **CBC**：180s/p99 预算 + success/salvage 两模式 | 高（防超时/保步骤分） | 低中 | 延迟实测 |
| P1 | **RGS**：官方 score_steps → 子目标谓词/进度头 | 中高 | 低中 | 32 个 info.json + 对齐 |
| P1 | **SPA-VLA**：部件可供性 token | 高 | 中 | 部件教师 + 单模型蒸馏 |

## 5. 修剪/暂缓

- **从零训练大模型**：不划算；WLA-1.0/GigaBrain-0.7/π0.5 已开源且许可证清晰。
- **真机在线 RL**：样本效率/安全/时间都不允许。
- **运行时 LLM/VLM API**：延迟/网络/规则风险；离线编译。
- **任务特定硬编码轨迹**：泛化差，可能违规；用部件谓词 + 意图状态。
- **激进 pivot / 大幅 base 运动**：默认静态；先探针，再按任务配置。
- **完整仿真 RL**：P3；规则/资产/时间不确定。
- **大规模 3D 生成增广**：P3；先把真实数据 + 轻量部件增广做好。
- **“再大一点的 VLA”**：不是本轮边际收益所在；本轮比的是决策治理。
- **每步 best-of-N**：延迟/抖动不可接受；只在事件点触发。
- **独立 verifier 模型**：单模型合规风险；改成同 checkpoint 的 head。

## 6. 为什么这版可能赢

- **对准口径**：成功率优先 → 先消灭 0%、再攻人类 trial、用 CI 而不是榜单噪声做决策。
- **对准数据**：32 任务都是部件交互 → 部件表示是比物体中心更合适的归纳偏置。
- **对准干扰**：官方 human 备注是撤销/移除/重置/阻塞 → IIR 分型响应直接打这个轴。
- **对准部署**：单模型 + 自部署 + N 端口 → 蒸馏而不是级联；CBC 保证 180s/p99。
- **对准风险**：Compliance Compiler 把“可能归零”的项前置，而不是最后一周才发现。
- **对准竞争**：2026 年的 verifier 论文证明推理时算力有效，但没人把它和意图/预算/单模型结合；这是 8 周内可做出的差异化。

## A. 结论

本轮把 RUBICON 3.0 升级为 **RUBICON 4.0 = IGX（Intent-Governed eXecution，意图治理执行）**。核心判断是：

> 上一轮解决的是“看得见、记得住”（部件可供性 + 可逆状态）；这一轮要解决的是“**什么时候信、什么时候验、什么时候修、什么时候放弃、算力花在哪**”。在成功率优先、人类干扰占 20%、单次 180s、单模型的赛制里，决策治理层的边际收益高于再大一点的 VLA。

IGX 由四层组成，全部在**同一个 checkpoint** 内：

1. **ISM（Intent State Machine）**：语言 + 历史 + 部件谓词 → 紧凑意图状态；只在事件点更新，保持承诺。
2. **ICV（Intent-Conditioned Verifier）**：在事件点对 K 个 action chunk 打分；用 **CFV（Counterfactual Failure-free Verifier）** 从成功演示构造负样本，不依赖失败 rollout。
3. **IIR（Intervention Intent Recognizer）**：把官方 `human_1/human_4` 细分为 undo/relocate/remove/reset/block/assist，并选择 repair/re-ground/scan/wait/abort。
4. **CBC（Competition Budget Controller）**：在 180s、p99、N 端口约束下分配验证算力；成功概率低时切 salvage 模式保步骤分。

底座保留 **SPA-VLA**（部件 token）、**RPSM**（可逆部件状态）、**Compliance Compiler**、**Endurance Governor**。

**最重要的口径**：官方排序是**总平均成功率优先**，步骤分只是平分后的 tie-breaker；10 次/任务 × 32 任务 = 320 次试验，p≈0.3 时总平均成功率的标准误约 **2.6pp**。因此：

- 1–2pp 的差距基本是噪声；不要为榜单波动改架构。
- 想把“排名更高”的概率做到约 80%，需要约 **3pp** 真实优势；约 90% 需要约 **5pp**。
- 人类干扰 trial 占 **20%**；human 成功率 +30pp → 总体 **+6pp**，是最高杠杆之一。
- 步骤分不是主目标，但 2.6pp 噪声意味着打平常见；RGS 是廉价 hedge。

## C. 比赛数学与策略

### C.1 排序公式

设任务 `i` 的第 `j` 次试验成功为 `y_ij ∈ {0,1}`，步骤分为 `q_ij ∈ [0,100]`：

```text
S = (1/32) * Σ_i (1/10) * Σ_j y_ij          # 总平均成功率
Q = (1/32) * Σ_i (1/10) * Σ_j q_ij          # 总平均步骤分
rank: S desc, then Q desc, then submission_date asc
```

### C.2 统计功效

总平均成功率的近似标准误：

```text
SE(S) ≈ sqrt( (1/32^2) * Σ_i p_i(1-p_i)/10 )
```

当所有 `p_i≈0.3`：

```text
SE(S) ≈ sqrt(0.3*0.7/320) ≈ 0.0256 = 2.56pp
95% CI ≈ ±5.0pp
```

真实优势与“排名更高”的概率（正态近似，两个模型各 320 trials）：

| 真实成功率优势 Δ | 差值 SE | P(观测排名更高) |
|---:|---:|---:|
| 0.5pp | 3.62pp | 55.5% |
| 1.0pp | 3.62pp | 60.9% |
| 1.5pp | 3.62pp | 66.1% |
| 2.0pp | 3.62pp | 70.9% |
| 2.5pp | 3.62pp | 75.5% |
| 3.0pp | 3.62pp | 79.6% |
| 4.0pp | 3.62pp | 86.5% |
| 5.0pp | 3.62pp | 91.6% |

**含义**：

- 1–2pp 的公开差距不能当真实优势；不要为榜单波动改架构。
- 想把“排名更高”的概率做到 ~80%，需要约 **3pp** 真实优势；~90% 需要约 **5pp**。
- 320 trials 下，检测 3pp 差异（80% power）需要约 3,700 次/组；本赛不可能靠增加 trials 解决，只能靠**更大的真实增益**和**降方差**。

### C.3 人类干扰的杠杆

10 trials/task 中，5 类泛化各 2 次，因此人为干扰占 **20%**。设 human trial 成功率 `p_h`，其余 `p_n`：

```text
S = 0.2 * p_h + 0.8 * p_n
ΔS = 0.2 * Δp_h + 0.8 * Δp_n
```

| 改进 | 总体增益 |
|---|---:|
| human 20% → 50%（+30pp） | **+6.0pp** |
| 非 human 30% → 35%（+5pp） | +4.0pp |
| 5 个 0% 任务 → 30% | +4.7pp |
| 5 个 70% 任务 → 80% | +1.6pp |
| 全部 32 任务 +2pp | +2.0pp |

**结论**：人类干扰 trial 的 30pp 改进，等价于“全部 32 任务 +6pp”，而且只需要攻 20% 的试验。IIR/RPSM 是最高杠杆的单项之一。

### C.4 任务组合优化

对每个任务维护 Beta 后验：

```text
p_i ~ Beta(α_i, β_i)
α_i = α0 + k_i
β_i = β0 + (n_i - k_i)
```

- 先验：Easy `Beta(3,3)`（均值 0.5）、Medium `Beta(2,4)`（0.33）、Hard `Beta(1.5,5)`（0.23）；也可统一 `Beta(2,2)`。
- 目标 1：最大化 `E[S] = (1/32) Σ E[p_i]`。
- 目标 2：最大化 `P(S > S*)`，用 Monte Carlo 从后验采样。
- 目标 3：降低 `Var(S)`，提高“单次评测抽到好成绩”的概率。
- 选择下一个调试任务：`score_i = (target_i - E[p_i]) / cost_i`，或 `UCB_i / cost_i`；对 `P(p_i < 0.05) > 0.5` 的任务加“no-zero”优先级。
- 成本 `cost_i` 可用历史调试时长、接触密度、任务时长、失败模式数估计。

**示例**：

- 5 个 0% 任务各提到 30% → `5×0.30/32 = +4.7pp`。
- 5 个 70% 任务各提到 80% → `5×0.10/32 = +1.6pp`。
- 1 个 0% → 50% → `0.50/32 = +1.6pp`。
- 10 个 30% → 40% → `10×0.10/32 = +3.1pp`。

**策略**：先消灭 0%，再攻 human trial，再攻接触密集任务；不要平均用力。

### C.5 两模式执行：success vs salvage

成功率优先，但在明显失败时，继续追成功可能连步骤分也丢掉。定义：

```text
if P_success < τ_s or T_remaining < T_need:
    mode = SALVAGE
else:
    mode = SUCCESS
```

- **SUCCESS**：最大化 full success；允许重试/修复；优先关键子目标。
- **SALVAGE**：最大化 `E[Q]`；完成高权重、低风险的剩余子目标；避免不可逆动作（例如把已插入的插头再拔出来、把已叠好的毛巾弄乱）。
- `τ_s` 建议 0.1；只在成功概率很低时启用，避免过早放弃。
- 用 RGS 的 score weights 计算 `q_t = Σ_k w_k * 1[s_k true]`，指导 salvage 选择。

### C.6 提交策略

- 规则：成功率相同 → 步骤分 → **提交日期早者靠前**。如果重提交会刷新日期，早提交没有 tie-break 优势；如果不刷新，早提交是免费保险。**未核实**，需向组委会确认。
- 建议：先提交一个稳定、低延迟的 fallback checkpoint，确保有有效成绩；IGX 只有在内部 LPL 上超过 fallback 才替换。
- 不要同时在不同端口跑不同 checkpoint 来“碰运气”；这可能违反单模型/公平性，且会污染成绩。
- 单任务通道只用于调试，不计分；不要在单任务通道上过拟合。

## D. IGX 总架构

### D.1 架构图

```text
4 views (head L/R, wrist L/R) + proprio + language
        │
        ▼
VLM backbone（WLA-1.0 / GigaBrain-0.7 / π0.5 / 其他允许的底座）
        │
        ├─ 16 part queries → part tokens
        │     ├─ existence / affordance
        │     ├─ 2D mask / centroid
        │     ├─ 3D point (canonical/relative frame)
        │     └─ descriptor
        │
        ├─ ISM（Intent State Machine）
        │     ├─ goal schema（语言）
        │     ├─ subgoal beliefs（RGS + RPSM）
        │     ├─ intervention mode（IIR）
        │     └─ budget/mode（CBC）
        │
        ├─ action expert → K candidate chunks
        │
        ├─ ICV verifier head → score(candidate | obs, intent)
        │
        └─ CBC selector → execute one chunk
```

### D.2 单模型合规

- 一个 checkpoint 包含：backbone、part head、intent head、verifier head、action head。
- 运行时**不加载** SAM3/PartSAM/LLM/VLM/第二个 policy；教师只在离线。
- 所有任务决策由同一计算图产生；不按任务切换权重；不把 task id 喂给模型。
- 安全 monitor 用规则式深度/几何/速度过滤，不引入第二个学习模型；若必须用人检测器，明确标注为 safety monitor，不参与任务决策。
- 在 model card 中说明所有头是同一计算图的一部分；提交 manifest 附静态检查。

### D.3 损失

```text
L = L_action
  + λ_part * L_part          # mask/centroid/affordance/3D
  + λ_intent * L_intent      # goal schema + subgoal phase + intervention
  + λ_ver * L_ver            # counterfactual ranking/BCE
  + λ_prog * L_prog          # rubric progress / predicate
  + λ_lang * L_lang          # language-part / paraphrase contrastive
```

- `L_action`：按底座选择 flow matching / diffusion / CE；不改底座动作头结构，只加 cross-attention。
- `L_ver`：同 checkpoint 的 verifier head；训练时用 counterfactual 正负对；推理时只做前向。
- `L_intent`：goal schema（动词/对象/目标/顺序）、subgoal phase（RGS）、intervention type（IIR）。
- `L_prog`：RPSM 谓词 + 官方 score_steps 的进度。
- 训练时对 part/intent/verifier 使用 confidence weighting；教师/标签不确定的帧不强制。

### D.4 运行时循环（伪代码）

```python
def act(obs, state):
    parts = part_head(obs)
    preds = predicate_head(parts, obs.proprio)
    event = detect_event(preds, state.prev_preds, obs, state)
    if event is not None:
        state.intent = update_intent(state.intent, event, obs, parts, preds)
        if event in {REGRESSION, PRE_CONTACT, HIGH_UNCERTAINTY, HUMAN}:
            cands = sample_chunks(action_expert, obs, state.intent, K=state.K)
            scores = verifier(cands, obs, state.intent, parts, preds)
            action = select(cands, scores, state.prev_action, state.budget)
        elif event == HUMAN:
            m = iir(obs, parts, preds, state.history)
            action = respond(m, state.intent, obs, parts)
        else:
            action = action_expert(obs, state.intent)
    else:
        action = action_expert(obs, state.intent)  # maintain commitment
    if state.budget_low or state.p_success < 0.1:
        state.mode = SALVAGE
    return action
```

关键：**非事件点不重算意图、不采样 K 个候选**；只在事件点花算力。这既降延迟，也避免 IntentVLA 说的 chunk 间意图冲突。

## E. ISM：意图状态机

### E.1 状态变量

| 变量 | 含义 | 来源 |
|---|---|---|
| `g` | goal schema：动词、对象/部件、目标、顺序、约束 | 语言 + 离线解析 |
| `a` | active subgoal index | RGS + RPSM |
| `s_k` | 子目标 k 的完成 belief | 谓词头 + 时序平滑 |
| `m` | intervention mode：none/undo/relocate/remove/reset/block/assist | IIR |
| `h` | human presence/proximity | 深度/部件 human query/规则 |
| `b` | remaining time / verify budget | CBC |
| `u` | uncertainty（action variance / verifier margin） | action expert + ICV |
| `mode` | SUCCESS / SALVAGE | CBC |

### E.2 事件定义

| 事件 | 触发条件 | 动作 |
|---|---|---|
| `START` | episode 开始 | 解析语言，初始化 `g`、`a=0`、`s=0` |
| `SUBGOAL_DONE` | `s_k` 从 false→true | `a = k+1`；检查是否全部完成 |
| `REGRESSION` | `s_k` 从 true→false | `m=undo`；`a=k`；触发修复/验证 |
| `HUMAN` | 人手进入/物体被移动/状态突变 | 运行 IIR；选择响应 |
| `PRE_CONTACT` | 进入插/挂/拉链/拧盖前的接触阶段 | 触发 ICV |
| `HIGH_UNCERTAINTY` | 候选方差高 / verifier margin 低 | 触发 ICV |
| `BUDGET_LOW` | `T_remaining < T_need` | 切 SALVAGE |
| `DONE` | 所有 `s_k` true | 停止/保持 |

### E.3 更新规则

- **事件触发**：只在事件点做语义推理；其余时间保持承诺（HINT）。
- **历史条件**：`m` 和 `a` 的更新用最近 1–2s 的 part/state 历史，避免单帧抖动（IntentVLA）。
- **迟滞**：`s_k` 的 true→false 需要连续 2–3 帧或高置信度，避免误报。
- **不可观测**：人手遮挡时保持 belief，不强行翻转；人离开后重检测。
- **不重置**：阶段切换不重置 episode 级意图；只有 `reset()` 清空。

### E.4 RGS：官方 score_steps 做子目标监督

- 抓取 32 个 `info.json` 的 `score_steps`；每个任务 2–5 步，合计约 94 步。
- 用离线 LLM/规则把每步解析成谓词：`(verb, object/part, target, order, weight)`。
- 用视觉变化点 + 夹爪事件 + CLIP 文本-图像相似度 + DTW，把每条 demo 分段到子目标。
- 训练一个轻量 subgoal head 预测当前子目标/进度；用 RPSM 谓词做一致性约束。
- 校验：2–3 个任务人工抽查；如果对齐差，退回无监督分段 + 顺序分配。
- 好处：稠密监督、可解释进度、步骤分 hedge、salvage 的权重来源。

### E.5 与 HINT / IntentVLA / DIAL 的关系

- **HINT**：意图稀疏变化于模式转换 → 我们用事件触发，不每帧重算。
- **IntentVLA**：历史条件短程意图解决观测别名 → 我们用历史 + 迟滞，避免 chunk 间冲突。
- **DIAL**：latent intent bottleneck → 我们的 `g/a/s` 是结构化 bottleneck，比纯文本更可验证；verifier 直接条件在它上面。
- 差异：我们把意图用于**验证/预算/干预响应**，而不只是动作生成。

## F. ICV + CFV：意图条件验证与无失败数据训练

### F.1 动机

- 只有成功演示，没有失败 rollout；DiVeR/RoboMonkey 的 success-vs-failure verifier 没有负样本。
- 每步 best-of-N 延迟/抖动不可接受；只在事件点验证。
- 验证必须“决策相关”：准确告警不够，还要来得及救、且不破坏本来成功的执行（RESCUE）。

### F.2 Counterfactual 负样本（CFV）

对每条成功 demo 的 `(o_t, a_t)` 构造负样本：

| 负样本 | 构造 | 目的 |
|---|---|---|
| 动作扰动 | EE 偏移 1–3cm、旋转 5–15°、关节噪声、速度 0.5×/1.5× | 学“最后几毫米” |
| 夹爪时序 | 早开/晚开 2–4 帧、反向 | 学抓取/释放时机 |
| 时间反转 | 反转 chunk 的时间轴 | 学插入/拉链/折叠方向 |
| 错子目标 | 同一 episode 的相邻阶段 chunk | 学“当前意图” |
| 错物体 | 同任务不同实例/相似语言的其他任务 chunk | 学目标 grounding |
| 交叉任务 | 同动词、不同对象的 chunk | 学语言-动作对齐 |
| 真实失败 | 我们自己的真机失败 rollout（少量） | 硬负样本/校准 |

要点：

- 负样本必须**同分布、可信但错误**；不能只是 OOD 噪声。
- 用 margin ranking loss 或 BCE + hard negative mining；不要只用随机负样本。
- 用 decision-critical weighting（DiVeR）：在候选方差高的状态加权；但权重来自 action-expert 表示方差，不需要额外标注。
- 离线验证：held-out 成功 demo 作为正样本，扰动作为负样本；看 AUC、top-1、校准；如果 AUC <0.7，停止扩大 verifier。

### F.3 Verifier 结构

```text
z_a = action_expert_repr(o, a)          # 动作表征
z_p = part_tokens(o)                    # 部件 token
z_i = intent_state(g, a, s, m, b)       # 意图状态
score = MLP([z_a, z_p, z_i])            # 1M 参数以内
```

- 用 FiLM/cross-attention 注入 `z_i`；不要只拼接语言。
- 输出 `P(success | o, a, z_i)`；同时输出 subgoal completion 辅助头。
- 温度缩放/ conformal 校准；保守阈值。
- 单模型：verifier head 与 action head 共享 backbone；不加载第二个模型。

### F.4 触发规则

```text
trigger = 1[event in {REGRESSION, PRE_CONTACT, HIGH_UNCERTAINTY, HUMAN}]
          * 1[P_fail > τ_f]
          * 1[T_remaining > T_cost(K)]
          * 1[budget_tokens > 0]
```

- `P_fail` 来自 verifier margin/动作方差/历史失败率。
- `T_cost(K)` = 采样 K 个候选 + 验证的时间。
- `budget_tokens` 是每 episode 的验证预算（例如 5 次）。
- 不是每个事件都验证；只在“值得救”时验证（RESCUE）。

### F.5 选择规则

```python
scores = [V(c, o, z_i) - λ_s * smooth(c, prev_action) - λ_t * latency(c)
          for c in candidates]
best, second = top2(scores)
if best - second > margin and best > threshold:
    return candidates[best]
else:
    return base_sample   # 保守回退
```

- `smooth`：与上一 chunk 的动作差、jerk；避免切换候选导致抖动。
- `latency`：候选的采样成本；优先低成本候选。
- `margin`：verifier 不确定时不切换，避免“验证反而更差”。
- 失败回退：如果 verifier 连续 N 次低 margin，关闭验证，回到 base policy。

### F.6 离线与闭环评估

- 离线：held-out demos + 扰动负样本；AUC、top-1、ECE、margin 分布。
- 半离线：用真实失败视频（runs 页未来开放）做 hard negatives。
- 闭环：5 任务 × 10 trials，base vs. best-of-N；记录成功率、步骤分、p99、决策数、验证次数。
- 统计：paired McNemar；Wilson CI；不要只看平均。
- K 消融：1/4/8/16；触发消融：每步/事件/随机；负样本消融：随机/硬/反事实。

### F.7 预期与停止条件

- 文献参考：DiVeR 真实 +13.6pp（有失败数据）；VeriVLA +14.7pp completion（有 latent world model）；VLA-ATTC 失败率 -50%（有 relative critic）。
- 我们的保守目标：+3–5pp overall；如果只有 +1–2pp，仍可能因降方差而有用，但不值得扩大。
- **停止条件**：离线 AUC <0.7，或闭环 5 任务 × 10 trials 增益 <1.5pp → 停止扩大 verifier，转 IIR/RGS/CBC。

## G. IIR：干预意图识别

### G.1 官方备注的语义结构

| 类型 | 代表任务 | 对模型的含义 |
|---|---|---|
| **撤销 undo** | T10 拔起插头、T14 拧回盖子、T16 翻开毛巾、T17 合上再打开笔盒、T19 拉开拉链、T27 拿走第二个碗 | 进度回退；只修复被撤销的子目标 |
| **移除 remove** | T12 拿走锁、T28 移动耳机、T29 移开外壳盖 | 目标消失；重扫描/安全停止，不能幻觉继续 |
| **重置 reset** | T24 把可乐/薯片放回传送带起点 | 重新分拣；不能假设已放好 |
| **移动底座/架子 relocate** | T08 挪架子、T11 动底座、T21 移架子、T25 挪底座 | 外参/场景记忆失效；重定位/重投影 |
| **阻塞 block** | T05 手握网口、T10 抓插头前移动、T26 移开网线/插口 | 目标不可达；等待/换目标/重试 |
| **普通位移** | 大多数 `human_1` | 部件重新检测 + 相对位姿更新 |

### G.2 分类与响应

| 类别 | 观测线索 | 响应 | 安全约束 |
|---|---|---|---|
| `UNDO` | 已完成谓词 true→false；物体回到之前状态 | 修复被撤销的子目标；不重跑全程 | 避开人手 |
| `RELOCATE` | 物体移动到新位置但可用；谓词可能仍 true | 重新 grounding；更新 centroid；继续 | 保持距离 |
| `REMOVE` | 物体消失；谓词无法满足 | 头部/腕部重扫描；找不到则 abort/salvage | 不幻觉 |
| `RESET` | 物体回到起点；进度丢失 | 从 reset 点重做；更新 belief | 时间预算 |
| `BLOCK` | 人手/手臂占用工作区；目标不可达 | 降速/暂停/等待；人离开后重试 | 人安全优先 |
| `ASSIST` | 人手把物体移向目标 | 让行；重新观测；继续 | 不和人抢 |
| `UNKNOWN` | 置信度低 | 保守等待/重观测 | 记录 |

### G.3 数据

- **合成**：
  - 反向播放成功 demo 的最后 2–5s → `UNDO`。
  - 图像修复/复制粘贴移除物体 → `REMOVE`。
  - 复制粘贴物体到新位置 → `RELOCATE`。
  - 物体放回起点 → `RESET`。
  - 合成手/臂 mask 覆盖工作区 → `BLOCK`。
  - 物体移向目标 → `ASSIST`。
- **真机**：8 个任务 × 2 类（human_1/human_4）× 10 次 = 160 episodes；用于校准/验证，不用于大规模训练。
- **硬负样本**：人手只是路过、没有改变状态；避免把所有手部出现都判为干扰。

### G.4 分类器与规则回退

- 输入：part tokens、谓词 delta、EE/夹爪、历史 1–2s、human proximity。
- 结构：轻量 Transformer/GRU + 分类头；与 ISM 共享特征。
- 规则回退：如果分类置信度低，用谓词 delta 规则（true→false=UNDO；物体消失=REMOVE；位置突变=RELOCATE；回到起点=RESET）。
- 迟滞：连续 2–3 帧才切换；避免抖动。
- 响应策略由 ISM 执行；IIR 只输出类别/置信度。

### G.5 与 RPSM 的关系

- RPSM 维护可逆谓词，检测“状态回退”。
- IIR 解释“为什么回退/谁造成的/该怎么响应”。
- RPSM 是状态层，IIR 是意图层；两者互补。
- 如果 IIR 不可用，RPSM 的规则回退仍能处理 undo/remove/reset 的大部分情况。

## H. CBC：比赛预算控制器

### H.1 延迟模型

```text
T_exec = H / f_c
T_decision = T_sample(K) + T_verify + T_exec
D = T_ep / T_decision
```

- `H = action_chunk_size`；`f_c` 控制频率（数据集 30fps，实际控制频率**未核实**，先按 30Hz 假设）。
- `T_sample(K)`：采样 K 个 chunk 的时间；可复用 VLM KV cache。
- `T_verify`：verifier head 前向；轻量 MLP 约 1ms 量级（DiVeR 报告）。
- `D`：180s 内可做的决策数。

示意（假设，不是实测）：

| H | T_exec @30Hz | K | T_sample | T_decision | D @180s |
|---:|---:|---:|---:|---:|---:|
| 8 | 267ms | 1 | 150ms | 417ms | ~431 |
| 8 | 267ms | 4 | 300ms | 567ms | ~317 |
| 8 | 267ms | 8 | 500ms | 767ms | ~235 |
| 8 | 267ms | 16 | 900ms | 1167ms | ~154 |
| 16 | 533ms | 8 | 500ms | 1033ms | ~174 |

结论：即使 K=8，30–60s 任务仍有足够决策数；但 37.6s 的长任务要留余量。**关键不是 K 越大越好，而是只在事件点用 K。**

### H.2 Token bucket

```text
budget = B  # e.g. 5 verification calls per episode
on event:
    if budget > 0 and T_remaining > T_cost(K) and P_fail > τ_f:
        verify with K
        budget -= 1
    else:
        base action
```

- `B` 按任务时长调整：短任务 2–3 次，长任务 5–8 次。
- 如果 p99 超预算，降低 K 或触发频率；不要牺牲 p99。
- 记录每次验证的收益（是否改变了选择、是否成功），用于离线校准。

### H.3 两模式与 salvage

- `P_success` 来自 verifier/进度/剩余时间。
- `P_success < 0.1` 或 `T_remaining < 10s` → SALVAGE。
- SALVAGE 下：按 RGS 权重选“高价值、低风险、可完成”的子目标；避免不可逆动作；优先保持已完成状态。
- 如果 SALVAGE 可能破坏已完成的子目标，停止并保持；安全第一。

### H.4 任务级预算分配

```text
for each task i:
    estimate p_i (Beta posterior)
    estimate gain_i = target_i - p_i
    estimate cost_i = debug_time + robot_trials
    ROI_i = gain_i / cost_i
allocate to top ROI, with no-zero priority
```

- 先 0% 任务；再 human trial 失败多的任务；再接触密集任务。
- 用 successive halving：5 tasks × 5 trials → top 2 → 10 trials；省机器人时间。
- 每周重估；连续两周无提升的任务标记“低弹性”，转预算。

### H.5 提交与回退

- 先提交稳定 fallback；IGX 只在 LPL 超过 fallback 时替换。
- 保留一个低延迟、无 verifier 的 fallback checkpoint；如果 p99 或崩溃，切回。
- 不在不同端口跑不同 checkpoint 碰运气；单模型/公平性风险。
- 关注 `runs.html` 的失败视频；建立 failure taxonomy，回流到 portfolio。

- 不使用未披露的私有数据；外部预训练模型按许可证列明。
- 训练/验证按任务和泛化类型分层；避免同 episode 泄漏。

## K. 实验设计

### K.1 E0–E7

| 编号 | 模型 | Verifier | Intent | Human | 目的 | 目标（假设） |
|---|---|---|---|---|---|---|
| E0 | base VLA | 无 | 无 | 无 | 基线 | 25–30% |
| E1 | +SPA | 无 | 无 | 无 | 部件底座 | +1–2pp |
| E2 | +ISM | 无 | task/progress | 无 | 意图状态 | +1–3pp |
| E3 | +CFV | 每步/固定 | 有 | 无 | naive best-of-N | +2–4pp，延迟风险 |
| E4 | +CBC | 事件触发 | 有 | 无 | 预算感知 | +3–5pp |
| E5 | +IIR | 事件触发 | 有 | 有 | 人类恢复 | human +10–30pp |
| E6 | +RGS | 事件触发 | rubric | 有 | 步骤分/子目标 | +0.5–1.5pp + Q |
| E7 | full IGX | 事件触发 | full | 有 | 最终 | +5–8pp（目标） |

这些是**目标/假设**，不是承诺；用 kill criteria 控制。

### K.2 消融

| 变量 | 取值 | 目的 |
|---|---|---|
| K | 1/4/8/16 | 算力-成功率曲线 |
| 触发 | 每步/事件/随机 | 事件触发是否更优 |
| Verifier 输入 | action repr / part tokens / latent world model / VLM | 哪种表征最有效 |
| 负样本 | 随机/硬/反事实 | CFV 是否必要 |
| 意图 | none/language/full ISM | 意图状态是否有用 |
| 校准 | none/temperature/conformal | 校准是否降低误切换 |
| 单模型 | 同 checkpoint vs 独立 verifier | 合规且不掉点 |
| Task ID | 无/有 | 证明不是靠 ID 过拟合 |

### K.3 指标

- 主：full success（每任务/总体）、95% CI。
- 次：step score（tie-break）、检查点完成率、超时率。
- 泛化：位置/干扰物/背景/未见物品/人为干扰分桶成功率。
- 人机：undo detection、repair success、time-to-recover、false alarm、intervention classification accuracy。
- 验证：AUC、top-1、ECE、margin 分布、切换率、验证收益。
- 部署：p50/p95/p99、jitter、显存、热节流、4h soak 漂移。
- 合规：单模型 hash 不变、无 task id、许可证清单、红队通过。

### K.4 统计

- 每任务 Wilson 95% CI；总体 bootstrap CI。
- base vs. IGX 用 paired McNemar（同任务/同初始条件）。
- 32 任务用 hierarchical Bayesian 汇总；报告 effect size 和 CI，不只 p 值。
- 10 trials/task 很小；不要对 1–2pp 的差异做过度解释。

### K.5 Kill criteria

- CFV 离线 AUC <0.7（hard negatives）→ 停止扩大 verifier；转 self-consistency + CBC。
- 闭环 5 任务 × 10 trials 增益 <1.5pp → 停止 best-of-N；转 IIR/RGS。
- p99 >0.8×T_exec 的调用 >5% → 降低 K/触发频率。
- human 恢复增益 <10pp（8 任务）→ 简化 IIR 为规则式 RPSM。
- 单模型解释被质疑 → 用同 checkpoint vs 独立 verifier 消融 + manifest；仍不行则去掉 verifier head，保留 ISM/CBC。

### M.2 单模型 manifest

- 一个 checkpoint：backbone + part head + intent head + verifier head + action head。
- 运行时不加载 SAM3/PartSAM/LLM/VLM/第二个 policy。
- 不按任务切换权重；不把 task id 喂给模型。
- `action.pivot` 输出安全值；默认静态。
- 静态检查：进程/依赖扫描；网络请求白名单；模型 hash 不变。
- 消融：同 checkpoint vs 独立 verifier，证明单模型不掉点。

### M.3 人机安全

- 工作空间包围盒、最大末端速度、最大关节速度、waist/base 限幅。
- 头部/腕部图像 + 规则式 human proximity → 降速/暂停。
- 暂停时保持姿态、记录 belief；人离开后重观测、继续。
- watchdog：推理超时、NaN、动作超限、端口断连 → 保持/安全退出。
- 红队：人手接近、遮挡、突然移动、拔插头、拿走物体。

### M.4 评测诚信

- 固定协议；所有 trial 落日志；不手工挑成功样本。
- 不在单任务通道上调参后假装通才成绩。
- 不针对 32 个任务写死坐标/轨迹；不把 task id 喂给模型。
- 外部数据/模型按许可证列明；不隐藏依赖。

## N. 创新点清单（持续迭代）

### N.1 P0-1：IGX 总架构

- **动机**：成功率优先 + 20% 人类干扰 + 180s + 单模型；上一轮的部件/状态层缺少决策治理。
- **与现有方案的差异**：HINT/IntentVLA/DIAL 有意图但没有验证/预算/干预响应；DiVeR/VeriVLA/VLA-ATTC 有验证但没有意图/预算/单模型约束。IGX 把四者合成一个单 checkpoint 的决策治理层。
- **技术可行性**：中。所有头共享 backbone；事件触发降延迟；可先做 verifier-only，再逐步加 ISM/IIR。
- **所需资源**：33k demos；8×A100/H100；G1 或高保真仿真；2–3 名人类干预员；8 周。
- **落地步骤**：baseline → 部件/子目标标签 → ISM → CFV → CBC → IIR → 全量评测。
- **风险**：复杂度高；verifier 无效；延迟；单模型解释。用 kill criteria 和 fallback 控制。

### N.2 P0-2：ICV + CFV（无失败数据的意图条件验证）

- **动机**：数据集只有成功演示；DiVeR/RoboMonkey 需要失败 rollout；单模型不能跑第二个 verifier。
- **与现有方案的差异**：用同分布 counterfactual 负样本（动作扰动/错子目标/时间反转/交叉任务）替代失败 rollout；verifier 条件在意图状态上；同 checkpoint 的 head。
- **技术可行性**：中高。离线可训练/评估；推理只加 1ms 级 MLP；关键是负样本质量。
- **所需资源**：33k demos；少量真实失败（50–100 episodes）；GPU；离线评估。
- **落地步骤**：构造负样本 → margin ranking/BCE → 离线 AUC/ECE → 小规模闭环 → K/触发消融。
- **风险**：负样本太简单/OOD；verifier 学风格不学成功；误切换。用硬负样本、校准、margin 回退、AUC kill criterion。

### N.3 P0-3：IIR（干预意图分型）

- **动机**：官方 human_1/human_4 是语义状态改变（undo/remove/reset/relocate/block）；统一“撤销后修复”会误判 remove/reset/block。
- **与现有方案的差异**：RPSM 只检测状态回退；IIR 解释意图并选择 repair/re-ground/scan/wait/abort；直接对应官方备注。
- **技术可行性**：中。合成数据可覆盖大部分类别；真机 160 episodes 校准；规则回退保底。
- **所需资源**：8 任务 ×2 类 ×10 次真机干预；人类演员；标注；GPU。
- **落地步骤**：taxonomy → 合成数据 → 分类器 → 响应策略 → 红队。
- **风险**：误报/漏报；unseen 干预；安全。用迟滞、规则回退、安全优先。

### N.4 P0-4：CBC（比赛预算控制器）

- **动机**：180s + p99 + N 端口；每步 best-of-N 会超时/抖动；步骤分是 tie-break。
- **与现有方案的差异**：RESCUE 式“决策相关”触发；token bucket；success/salvage 两模式；任务级 ROI。
- **技术可行性**：高。规则式即可；不需要额外训练；可与任何 VLA 组合。
- **所需资源**：延迟实测；评测日志；少量机器人 trial。
- **落地步骤**：instrument → 延迟模型 → 触发校准 → 闭环 A/B → 全量。
- **风险**：触发阈值错；p99 抖动；salvage 过早。用保守阈值、p99 guard、kill criteria。

### N.5 P1：RGS（rubric-grounded subgoals）

- **动机**：32 任务有 94 个官方评分点；成功需要全部；步骤分是 tie-break；免费稠密监督。
- **与现有方案的差异**：上一轮 Rubric Compiler 只解析分数；RGS 把评分点对齐到帧，训练子目标/进度头，并用于 salvage。
- **技术可行性**：中高。CLIP+DTW+视觉变化点；无需人工大规模标注；抽查校准。
- **所需资源**：32 info.json；33k demos；GPU；少量人工抽查。
- **落地步骤**：抓取 → 解析谓词 → 分段 → 训练 → 评估。
- **风险**：对齐噪声；rubric 歧义；过拟合评分点。用多方法一致性、人工抽查、成功率主指标。

### N.6 P1：SPA-VLA（部件可供性）

- **动机**：32 任务都是部件级交互；物体级 3D 不够；未见物品/干扰需要部件语义。
- **与现有方案的差异**：教师离线蒸馏进单模型；16 个 part queries；部署不跑第二个分割模型。
- **技术可行性**：中。SAM3/PartSAM 教师；伪标签；轻量头；单 checkpoint。
- **所需资源**：33k demos；教师模型；GPU；人工验证 1–2k 帧。
- **落地步骤**：教师伪标签 → 质量控制 → 学生微调 → 消融。
- **风险**：透明/反光/小部件；part query 坍塌；教师误差。用多视角/腕部/置信度/oracle-mask 上限。

### N.7 P1：RPSM（可逆部件状态）

- **动机**：官方干扰会撤销已完成子目标；进度不能单调。
- **与现有方案的差异**：部件级谓词 + 可逆 belief + 撤销增广；与 IIR 互补。
- **技术可行性**：中。谓词 8–12 个跨任务通用；时序平滑；规则回退。
- **所需资源**：part tokens；proprio；合成 undo；真机验证。
- **落地步骤**：谓词库 → 标签/增广 → 分类器 → 闭环。
- **风险**：谓词过细；遮挡/透明；误报。用通用谓词、迟滞、置信度。

### N.8 P1：Compliance Compiler

- **动机**：单模型/180s/许可证/人机安全/无 task id；一项不清可能归零。
- **与现有方案的差异**：规则→实现→测试的闭环；运行时 monitor；提交 manifest。
- **技术可行性**：高。工程/流程为主。
- **所需资源**：规则文本；部署；红队；法律/许可证检查。
- **落地步骤**：规则表 → 实现 → 测试 → manifest → 红队。
- **风险**：规则解释变化；外部数据/模型不清。用保守解释、fallback、向组委会确认。

### N.9 P1：Endurance Governor

- **动机**：N 端口、长时并发、4 路视频；p99/热/内存会吃掉成功率。
- **与现有方案的差异**：服务续航 + 语义续航 + 验证算力预算；不是省电。
- **技术可行性**：高。共享后端 + 会话隔离 + 动态 batching + 降级。
- **所需资源**：N 端口；4h soak；监控；GPU。
- **落地步骤**：部署 → 压测 → 降级 → soak → 红队。
- **风险**：并发/热/内存；验证算力打满。用 token bucket、批处理、p99 guard。

### N.10 P2：Regime Router（泛化类型识别）

- **动机**：5 类泛化各 2 次；不同失败模式；可调制策略。
- **与现有方案的差异**：从场景/语言/干扰推断当前 regime；调制 verifier 阈值/视觉依赖。
- **技术可行性**：低中。合成标签；可能学到评测者虚假线索。
- **所需资源**：分层数据；分类器；验证。
- **落地步骤**：标签 → 分类器 → 调制 → 消融。
- **风险**：虚假线索；规则风险；收益不确定。P2，先观察。

### N.11 P2：Paraphrase-Invariant Intent

- **动机**：每任务 5 条复述；评测可能用未见措辞。
- **与现有方案的差异**：留一法 + 回译/约束图；goal schema 而不是 raw tokens。
- **技术可行性**：高。数据现成。
- **所需资源**：tasks.parquet；训练；评估。
- **落地步骤**：按复述划分 → 训练 → 留一评估 → 消融。
- **风险**：低；可能提升有限。

### N.12 P2：Latent World Model Rollout

- **动机**：chunk 级 verifier 是短视的；多步后果预测可提升长程。
- **与现有方案的差异**：VeriVLA/CheckVLA 用独立 world model；我们做同 checkpoint 的 latent consequence head。
- **技术可行性**：低中。数据/算力/复合误差。
- **所需资源**：GPU；视频/状态；训练。
- **落地步骤**：latent prediction → 离线评估 → 集成 → 消融。
- **风险**：复合误差；延迟；收益不确定。P2/P3。

### N.13 暂缓/不做

- 从零训练大模型；真机在线 RL；运行时 LLM/VLM API；任务特定硬编码；激进 pivot/base；完整仿真 RL；大规模 3D 生成；每步 best-of-N；独立 verifier 模型。

## P. 开放问题

1. **外部数据/模型**是否允许？若允许，Apache-2.0 底座（WLA-1.0/GigaBrain-0.7/π0.5）可用；若不允许，挑战数据微调 + IGX 仍是 fallback。
2. **N 台机器人/端口**：README 示例 N=3，具体值待公布；并发/批处理/显存按 N 配置。
3. **控制频率**：数据集 30fps；实际控制频率未知；CBC 的延迟模型需实测。
4. **评分公式**：每任务步骤分是 trial 平均还是其他聚合？Q 是否按任务归一化？未读。
5. **排名/入围**：榜单入围条件、成绩记录方式、提交日期如何记录？未读。
6. **单模型定义**：辅助头/安全 monitor 是否算“多个模型”？当前设计把所有任务决策放进一个 checkpoint，安全 monitor 规则式。
7. **任务 ID**：评测是否把 task id 传给模型？我们主动不用；若官方只给 task id 不给语言，需要适配。
8. **语言**：评测用 5 条复述、未见复述、还是中文？未核实；先做留一法/约束图。
9. **人为干扰协议**：脚本化还是自适应？`human_1/human_4` 的时序/频率未知；先按备注构造测试。
10. **base/waist 限制**：是否允许移动底座/腰部？未核实；默认静态 + 探针。
11. **真实榜单**：公开榜仍是占位；真实排名/强基线不可见；不要用假分数做决策。
12. **提交日期 tie-break**：重提交是否刷新日期？若刷新，早提交无优势；需确认。
13. **runs 页开放时间**：完整评测视频何时开放？开放后优先做 failure taxonomy。
14. **派生标签许可证**：部件/子目标/干预标签由我们生成，源数据 Apache-2.0；提交时保留 NOTICE。
