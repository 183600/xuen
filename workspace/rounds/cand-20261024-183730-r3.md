# 第 8 轮 · RECON：异常检测的终点不是“判失败”，而是“还剩多少可恢复时间”

> 检索/复核日期：**2026-10-24（UTC）**。赛事身份再次核实：用户所指仍是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API。本轮任务序号为第 3 轮，承接状态文件中的第 7 轮 PILOT-GPR，不推倒重来。
> 本轮三个灵感词：**异常检测、跨任务泛化、平衡控制**。我先各自钉到本轮核实到的一手事实上，再合成主判断：**把“异常检测”从二分类的“会不会失败”改写成决策论的“还有多久进入不可恢复区”，用抓取/支撑/插入/运动/时间五类平衡裕度做跨任务状态表示，在同一个 checkpoint 里用 TTU（time-to-unrecoverable）头触发共享恢复选项。** 第 7 轮把终局放置当作“闸门 + 步骤分大头”；本轮两条新事实修正了后半句：手册明确**成功率优先、步骤分只做 tie-break**；同时 `action.pivot` 的数据分析显示它不是一个摆设，而是包含躯干姿态、基座运动与高度的全身通道——平衡控制第一次有了接口层的抓手，也有了必须先修的坑。

## 0. 本轮先核实：六个会改变判断的事实

### 0.1 评分口径：成功率优先，步骤分只是 tie-break（对第 7 轮的重要修正）

参赛手册（中/英两版，2026-10-24 抓取）原文：

> “实时榜单按32个任务的 **总平均成功率** 进行排序，成功率相同时按总平均步骤分排序，若仍相同，则提交日期较早的模型排序靠前。”

同一份手册还写明：每个任务执行 **10 次**独立运行，5 类泛化各出现 **2 次**；单次真机执行最大 **180 秒**；只设通才单模型赛道；模型由选手自行部署；另有不计分的单任务测试通道。

这与首页的宣传语“按平均成功率与步骤分 **综合** 排序”存在措辞冲突。我的处理是：**以手册为准，把成功率当第一目标，步骤分当 tie-break**；同时把首页的“综合”当作可能的实现差异，等真实榜单出现后再校准。这个修正很重要：第 7 轮用“终局步骤占 39.8%、放置类步骤占 59.7%”论证放置的杠杆，但若步骤分只是 tie-break，那么“放置值 59.7% 的分数”这个说法就不再是主要理由。**终局放置仍然是 32/32 任务的成功闸门，这个事实不变；变的是我们不该为了部分分牺牲成功率。**

### 0.2 10 次/任务、每轴 2 次：统计噪声比想象中大

32 任务 × 10 次 = **320 个计分 trial**。若真实成功率 p≈0.30，总体标准误约 `sqrt(0.3×0.7/320)=2.56pp`。也就是说，**+3pp 的提升只有约 1.2 个标准误**，单次榜单很难区分；+5pp 才比较稳。每个任务只有 10 次，任务级成功率的分辨率是 10%；每个轴每任务只有 2 次，单任务轴级结论几乎不可用。轴级诊断必须把 32 个任务合起来（每轴 64 个 trial，SE≈5.7pp），并且用配对/分层分析。这个事实决定了：**不要追 1–2pp 的微调，要做能在多个任务上同时生效的机制；不要用 2 个 trial 的轴级差异做模型选择。**

### 0.3 榜单/运行记录仍是占位，不能把“榜首 29.7%”当真实 SOTA

`leaderboard.html` 页面顶部写 “Ranking · Live”，但底部仍是“即将发布 / Coming Soon”；`leaderboard_data.json` 仍写着 `"generated_from": "gen_leaderboard.py"`，发布时间为 **2026-10-08**；`details.html` 的 32 个任务视频全部是“测试视频占位，后续可替换为真实视频文件”；`runs.html` 也是占位（`256 / 256`，8 个模型 × 32 任务）。8 个“模型/用户”里，模型名借用了真实模型家族（MolmoAct2、WALL-OSS-0.5、DreamZero、Spirit-v1.5、DM0、PI-0.5、GigaBrain-0、GR00T N1.5），但用户是虚构的，数值由脚本生成。

结论：**不能分析“榜首方案”的真实做法，也不能把 29.7% 当作竞争基线。** 它最多是一个弱先验：8 个占位模型的“步骤分 − 成功率”平均约 +8.6pp，暗示失败多发生在后段步骤；但这是脚本生成的，不能作为证据。真正可用的信息是规则、任务定义、数据和接口。

### 0.4 数据规模与时间线：32 任务、1828 万帧、169.28 小时，2026-10-14 更新

HF collection 的 32 个数据集，`lastModified` 基本都在 **2026-10-14**（HangCup 为 2026-10-14T06:35:13Z）。用 datasets-server 的 `num_examples` 求和：**18,282,246 帧**；按 30fps 折算 **169.28 小时**，与官方“169 小时”一致。官方口径约 **32,000** 条演示；HF 各任务 969–1,530 条，合计约 33k。数据格式为 LeRobot v3，四路相机（`head_stereo_left/right` + `wrist_left/right`），双臂关节、EE 位姿（base 与 torso 两套坐标）、夹爪、lower body、`action.pivot` 等。

这意味着：数据量足够做“成功演示上的正常性建模”，但**没有失败数据**；异常检测必须是 one-class / 合成异常 / 仿真反事实的组合，而不是监督式失败分类。

### 0.5 本轮最重要的数据发现：`action.pivot` 是全身姿态通道，不是摆设

提交 README 的动作表里，`action.pivot` 是 **shared** 键（joint 和 ee 两种控制空间都必须返回），形状 `[7]`。数据集里的字段名是：

```text
action.pivot = [vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]
action.base_command = [vx, vy, angle_z, height]
```

我在两个任务上做了全量/抽样分析：

- **HangCup**（130,565 帧，719 个 episode 的一个 parquet 分片）：`vx/vy/yaw ≈ 0`，`pivot_3=0`、`pivot_4=0.15`、`pivot_5=0`，`height=0.74`（少数 episode 起步阶段 0.7213–0.74）；整体标准差仅 0.0022。基座是静止的，躯干姿态是任务级常数。
- **OrganizeTools**（122,499 帧，113 个 episode 的一个分片）：`pivot_3` 与观测到的 `waist_state_joint[0]`（腰 yaw）相关系数 **0.733**；`pivot_4` 与 `waist_state_joint[2]`（腰 pitch）相关系数 **0.867**；基座速度非零帧占比约 **0.21% / 0.13% / 0.03%**（vx/vy/yaw），`vx` 最大 0.439，`height` 在 0.6946–0.74 之间变化。这个任务里机器人确实会**移动基座、调整高度、改变躯干俯仰**去够工具架。
- 其他任务抽样（first-rows + 三个 offset）：多数是 `[0,0,0,0,0.15,0,0.74]`；例外包括 FoldTowel/StorePaddle 的 `pivot_4=0`、ArrangeTestTubes 的 `height≈0.689`、Unlock 的 `height≈0.717`、PaperCupStacking 的 `height≈0.694`、PickOutBatteries 的 `height≈0.736`、PackPhone 的 `height≈0.739`、FruitSorting 的 `height≈0.737`。

而参考实现 `example_policy.py` 对 `action.pivot` 返回的是 **全零**：

```python
action["action.pivot"] = np.zeros((T, 7), dtype=np.float32)
```

如果 pivot 是绝对目标，全零意味着把高度/躯干姿态命令到 0，可能是灾难性的；如果是增量或“保持”，全零才是中性。**接口没有写清楚语义**。这是一个必须先验证的工程风险，也是一个便宜的巨大收益：**Pivot Guard——按任务回放演示中的名义 pivot（高度、躯干姿态），只做安全范围内的平滑，不把未验证的零发出去。** 这条同时把“平衡控制”从抽象口号变成了一个具体的接口层变量：G1 站在桌边，躯干俯仰和基座高度会改变工作空间与重心；我们不一定要做闭环全身平衡，但至少不能把姿态命令到分布外。

### 0.6 异常检测文献已经很拥挤，但都停在“检测/回滚”，没有回答“还来不来得及救”

本轮检索到的 2026 年工作：

- **SAFE**（多任务 VLA 失败检测，用 VLA 内部特征，需要成功/失败 rollout）；
- **VLA-FAIL**（LLMD 末层特征 Mahalanobis + ACC 动作块一致性，**不需要失败数据**，提出 AUCPDT 指标）；
- **ActProbe**（纯动作空间 TCE + ACM，**在未见任务上 early-detection ROC-AUC +9.0%**，说明动作信号有跨任务性）；
- **RC-NF**（CVPR 2026，robot-conditioned normalizing flow，仅正样本，**<100ms**，触发 state-level rollback / task-level replanning）；
- **Foresight**（action-conditioned world model latent + functional conformal prediction，policy-agnostic，长程任务）；
- **ReconVLA**（conformal uncertainty + state-space outlier detection）；
- **Kintsugi-VLA**（用仿真精确恢复状态，测“interventional recoverability”，发现可恢复性沿失败轨迹**非单调**，存在“低可恢复性前沿”；恢复数据比均匀采样 +5.8/+6.7pp）；
- **Nefzer & Asfour 2026**（人形 ARMAR-DE，手部 proprioception 在 **50% 执行时间**达到 **96.97%** 早期失败检测，优于力/ToF）；
- **Brace Yourself**（G1 用一只手撑住环境，发力从 **13.5N** 提到 **60N**）；
- **Blind Dexterity**（G1 纯本体感觉的全身操作，关节编码器读数在接触下形成“全身触觉通道”）；
- **Current as Touch**（用电机电流 + 关节状态预测 compliance reference，不需要力传感器）。

这些工作合起来说明两件事：**检测本身已经商品化；真正缺的是“在还能救的时候，选择救法”的运行时决策层。** 这就是本轮的主判断。

## 1. 三个灵感词，各自钉到事实上

### 1.1 异常检测：从“判失败”到“判可恢复性”

现有检测器优化的量是 AUROC、AUCPDT、检测提前量；但比赛的优化量是**episode 成功率**。一个在 50% 时间点报警、但状态已经不可恢复的检测器，对成功率没有价值。Kintsugi 的“低可恢复性前沿”正是这个问题的证据：可恢复性沿失败轨迹先升后降，存在一个点，过了就救不回来。Nefzer 的结果则说明：**手部本体感觉可以在 50% 执行时间给出高精度预警**，而 UniBot 的观测里恰好有双臂关节、夹爪开度、EE 位姿——我们不需要额外传感器，就能构造类似的“efference copy / 跟踪误差”信号。

所以本轮把异常检测的目标改写为：

```text
不是：P(failure | s_t)
而是：TTU(s_t) = 在继续当前动作的前提下，距离“最小平衡裕度归零”还有多久
      R(s_t, b) = 在剩余预算 b 内，存在某个恢复选项 r 使任务成功的概率
      触发条件：TTU < T_recover(r*) + ε  且  R_recover(r*) > R_continue + δ
```

异常 = 平衡裕度的**非预期快速下降**（滑落、卡死、被人移动、碰撞），而不是“画面看起来不一样”。这一步把“异常检测”从一个黑箱分数变成了可解释的物理量。

### 1.2 跨任务泛化：从“任务 ID”到“物理裕度”

2026 年的跨任务工作给了两条路：

- **参数化程序记忆**：VLA-Pro 把任务相关的 LoRA 适配器当“程序记忆”，推理时按多模态上下文检索融合；仿真相对提升最高 **207%**，真机 **5.8% → 65.0%**。
- **技能-动作对**：Decompose & Recompose 把演示分解成可解释的 skill–action 对，在 AGNOSTOS 上做组合推理；AGNOSTOS 本身说明现有 VLA 在未见任务上仍然很弱。
- **诊断而非方法**：Embodied Interpretability 的 NMR（nuisance mass ratio）表明，模型对任务无关特征的依赖程度可以预测泛化；这给了一个便宜的 checkpoint 选择指标。

但 UniBot 的规则是**单模型完成全部 32 个任务**，per-task LoRA 有合规风险。于是我不走“每任务一个适配器”，而走**任务无关的物理表示**：失败物理（滑、倒、卡、偏、遮挡、被人移动）在 32 个任务里是共享的；把状态表示成“抓取裕度、支撑裕度、插入裕度、运动学裕度、时间裕度”，就可以用一个跨任务的头去学，并用 **leave-one-task-out** 验证它是不是真的在学物理，而不是记任务 ID。跨任务泛化在这里不是“零样本新任务”，而是**跨任务共享失败表示 + 跨任务共享恢复选项**。

### 1.3 平衡控制：三个层次，别把“机器人站稳”当成全部

- **物体平衡**：堆叠/放置的支撑多边形与重心投影。T20 纸杯、T21 盘子、T25 杯子、T27 碗、T07 相框、T03 袋子直立——这些任务的失败常常是“放上去倒了”，而不是“没抓到”。这是可以用立体视觉 + 几何算出来的。
- **接触平衡**：插入/拧盖/拉拉链时的力与对齐。T10 插头、T26 网线、T32 注射器、T14 药瓶、T12 锁、T19/T31 拉链——失败常常是“卡住/打滑/没对准”。UniBot 没有力/触觉，但**指令关节位置与观测关节位置的跟踪误差**可以作为接触/阻力的代理；Blind Dexterity 和 Current as Touch 都支持“本体感觉含接触信息”。
- **机器人平衡**：G1 站在桌边，躯干俯仰、基座高度、基座平移都会改变重心与工作空间。数据告诉我们：多数任务基座静止、躯干姿态是任务级常数；OrganizeTools 会移动基座/调高度。**我们不主张做激进的闭环全身平衡**（没有 IMU/CoM 反馈，风险高），而是做 **Pivot Guard**：回放名义姿态、限幅、只在演示分布内做小偏差；把“平衡”作为**不要制造失衡**的约束，而不是一个新的控制回路。

一句话：**平衡控制在本轮的角色是提供“裕度”这个共同货币**——物体、接触、机器人都用“距离失败边界还有多远”来描述。异常检测是裕度的非预期下降，恢复是裕度的重建，跨任务是裕度表示的共享。

## 2. 本轮主判断：RECON（Recoverability-Conditioned Intervention）

### 2.1 一个更锋利的失败模型

结合 0.1 的评分口径与 0.6 的文献，我给本轮的主判断是：

> **在 <30% 的成功率区间，最大的边际收益不是“再换一个更大的 VLA”，而是“让已经在执行的策略在失败前被救回来”。检测器已经很多，但没有人把“可恢复性”当成运行时决策变量；而 UniBot 的 180 秒预算、32 任务共享的失败物理、以及单模型约束，恰好让“一个 checkpoint + 共享恢复选项”成为最合适的形态。**

为什么不是继续加码终局放置？因为终局放置是**成功闸门**，但它只是“最后一厘米”；在它之前，抓取滑落、运输碰撞、目标被移动、插入卡死已经发生了。第 7 轮的 SVL 是“放完再检查”，本质是 post-hoc；本轮把它升级为**pre-failure 的连续监控 + 恢复**。为什么不是做一个通用异常检测器？因为背景泛化会把“换了桌布”误报成异常；我们必须做**nuisance-invariant** 的异常检测，把“背景/干扰物/位置变化”与“真正的失败前兆”分开。为什么不是做一个视频 world model？因为 p99 延迟和 180 秒预算不允许；一个**裕度动力学模型**（预测 margin 的下一步，而不是像素）更便宜、更可解释，也更容易跨任务。

### 2.2 收益算术：从“检测准确率”换到“成功率”

设基线成功率 p，失败率 f=1−p；失败中**增量可恢复**（基线自己不会救回来）的比例 ρ；恢复选项成功率 q；成功 episode 上误触发率 α；误触发把成功变成失败的概率 c。则：

```text
ΔS ≈ f · ρ · q  −  p · α · c
```

保守取 p=0.30、ρ=0.20、q=0.50、α=0.05、c=0.30：

```text
ΔS ≈ 0.70×0.20×0.50 − 0.30×0.05×0.30 = 0.070 − 0.0045 ≈ +6.5pp
```

这不是“检测 AUROC +5 个点”，而是**端到端成功率 +6.5pp**；在 320 trial、p=0.30 下约 2.5 个标准误，值得押。若 ρ 只有 0.10，则 +3.0pp；若 ρ=0.30、q=0.70，则 +14.2pp。真实值必须用调试槽测，不能拍脑袋。

关键推论：**恢复的价值取决于“失败是否还来得及救”，而不是“检测是否早”。** 所以我们要优先选**高可恢复性任务**做第一轮：T27 叠碗、T10 插头、T26 网线、T20/T21/T25 堆叠/摆盘、T07 相框、T32 注射器；T16 毛巾、T19 拉链、T03 袋子直立这类低可恢复性任务，先不投入主火力。

### 2.3 为什么这比第 7 轮的 SVL 更该做

| 维度 | 第 7 轮 SVL | 本轮 RECON |
|---|---|---|
| 时机 | 释放后 | 失败前（TTU） |
| 范围 | 单个放置点 | 全任务、跨任务 |
| 判定 | 手写谓词 + 稳定性 | 学习裕度动力学 + 谓词 |
| 恢复 | nudge/regrasp/retry | 共享选项库 + 预算决策 |
| 数据 | 成功演示 | 成功演示 + 合成异常 + 仿真反事实 |
| 合规 | 确定性代码 | 同一 checkpoint 的辅助头 + 确定性几何 |
| 评分对齐 | 步骤分/成功率 | **成功率优先** |

第 7 轮的 SSG/PGL/OPT/ICR/NRB 不丢：SSG 仍是步骤进度骨架，PGL/OPT 仍是放置专项，NRB 升级为恢复选项的训练数据，DebugLoop 升级为 RECON 的真机验证主回路。**变化的是预算分配：从“放置专项 40%”改为“运行时恢复 40%、放置专项 25%、数据/孪生 20%、工程 15%”。**

## 3. 方案轮廓：RECON = EQUIL + MDM/TTU + ROL + Pivot Guard

```text
语言(160条复述) → SSG 步骤图 → 当前步骤 s_t、剩余预算 b_t
                                   │
   4 相机 + 关节/EE/夹爪/躯干 ──► EQUIL 平衡裕度观测器（确定性几何 + 本体）
                                   │  m = [m_grasp, m_support, m_insert, m_kin, m_time]
                                   ▼
                    MDM 裕度动力学（同一 checkpoint 的辅助头）
                     预测 m_{t+1..t+H}、TTU 分位数、失败模式
                                   │
                    ┌──────────────┴──────────────┐
                    │ TTU < T_recover + ε ?        │
                    │ R_recover(r*) > R_continue ? │
                    └──────────────┬──────────────┘
                        否 │                     │ 是
                           ▼                     ▼
                   继续执行 VLA chunk      ROL 恢复选项（同一 checkpoint 的 token 条件）
                   （GPR-VLA 主干）        re-localize / re-grasp / re-align /
                                           re-place / re-insert / re-support /
                                           step-reset / abort
                                   │
                                   ▼
                    Pivot Guard（名义躯干/高度/基座）+ Compliance Governor（跟踪误差）
```

一句话：**把“异常”定义成平衡裕度的非预期下降，把“恢复”定义成在预算内重建裕度，把“跨任务”定义成共享裕度表示与恢复选项；所有学习参数在同一个 checkpoint 里，几何/阈值/守卫是确定性代码。**

## 4. 与上一轮的关系：保留、升级、新增、修剪

- **保留**：GPR-VLA 主干 + WLA-1.0-Base 底座；TLE/ACP/GF 数据引擎（收窄到 8 个放置/插入任务）；AH-TP/Endurance Governor；Compliance Compiler；SSG；PGL；OPT；ICR（降权）；NRB（升级）；L2L（低优先）；TCLB（降级）；FLEET 检查单。
- **升级**：SVL → **RECON**（pre-failure + post-release 统一）；NRB → **恢复选项训练库**（官方 human 备注剧本 + 合成失败）；DebugLoop → **RECON 的真机验证主回路**（T27/T10 优先）；SSG → 给 TTU 提供步骤进度与时间预算。
- **新增**：**EQUIL** 五类裕度观测器；**MDM/TTU** 裕度动力学与可恢复性头；**ROL** 跨任务恢复选项库；**Pivot Guard**；**Compliance Governor**；**PAR** 姿态感知 reach（可选）；**NMR** checkpoint 选择（可选）；**任务可恢复性分诊**。
- **修剪**：通用黑箱异常检测器（会被背景变化误报）；视频 world model 进主路径（太重）；per-task LoRA（单模型合规风险）；全任务主动移动基座（只在 T15 演示中出现，别处是 OOD）；把步骤分当主目标的预算逻辑（改为成功率优先）；全 32 任务高保真孪生（只做 8 个关键任务）；运行时仿真/MPC；仿真 RL；布料/拉链/透明全物理；WMA-0 进主路径。

## 5. 风险与合规（先立后破）

- **单模型边界**：所有学习参数（主干、action expert、SSG 谓词头、margin/TTU 头、失败模式头、恢复 token embedding）保存在**一个 checkpoint**；没有 per-task 权重；推理时不调用外部学习型 detector。EQUIL 的几何、Pivot Guard、Compliance Governor、conformal 阈值都是确定性代码/常数。模型卡写清楚。
- **没有失败数据**：用成功演示学“正常裕度动力学”；用合成异常（遮挡、滑落、卡死、目标平移、动作延迟）和仿真反事实（Kintsugi 式状态恢复 + 分支）做弱监督；只用调试槽做验证，不用它调权重。
- **背景/干扰物不是失败**：必须做 nuisance-invariant 训练——同一轨迹换背景/加干扰物是“正样本对”，真正的失败前兆才是“负样本”。否则背景轴会带来大量误报。这是本轮与通用异常检测最大的区别。
- **Pivot 语义未核实**：绝对/增量/保持未知；默认回放名义 pivot，绝不发未验证的零；本地 `example_env.py` + 一个调试槽验证。
- **透明/布料任务**：几何裕度失效；回退到动作/本体/步骤进度信号，不做支撑多边形。
- **误触发代价**：conformal 校准 + 成本敏感触发 + 每 episode 干预上限（2–3 次）；长程任务（T16/T17/T31）上限 1–2 次。
- **统计噪声**：320 trial；目标 +5pp；任务级配对；不要用 2 个 trial 的轴级差异做结论。
- **榜单占位**：不把 29.7% 当基线；以手册口径和任务语义为准；真实榜单出现后重跑假设。
- **外部数据/合作**：规则只读到 2.2，外部数据是否允许未确认；L2L 默认 OFF，邮件确认后再开。

## 6. 一句话押注

**把异常检测从“判失败”改写成“判还剩多少可恢复时间”：用抓取/支撑/插入/运动/时间五类平衡裕度做任务无关状态表示，在同一个 checkpoint 里用 TTU 头触发共享恢复选项，并用 Pivot Guard 把全身姿态锁在演示分布内——这是本轮最值得押注的方向。**

### 1.4 `action.pivot`：被忽视的全身姿态通道（本轮核心数据发现）

提交接口把 `action.pivot` 列为 **shared** 动作（joint 和 ee 两种控制空间都必须返回），形状 `[7]`。数据集字段名：

```text
action.pivot       = [vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]
action.base_command= [vx, vy, angle_z, height]
```

**HangCup 全量分片（130,565 帧，719 episodes）**：

```text
pivot min  [-0.0000, -0.0000, -0.0000, 0.0000, 0.1500, 0.0000, 0.7213]
pivot max  [ 0.0033,  0.0001, -0.0000, 0.0000, 0.1500, 0.0000, 0.7400]
pivot std  [ 0.0000,  0.0000,  0.0000, 0.0000, 0.0000, 0.0000, 0.0022]
```

基座静止；`pivot_4=0.15`、`height=0.74` 是任务级常数；少数 episode 起步阶段高度 0.7213–0.74。

**OrganizeTools 全量分片（122,499 帧，113 episodes）**：

```text
pivot min  [-0.0000, -0.0000, -0.7625, -0.4057, 0.0000, 0.0000, 0.6946]
pivot max  [ 0.4388,  0.1238,  0.8000,  0.4382, 0.6096, 0.0000, 0.7400]
pivot std  [ 0.0055,  0.0011,  0.0125,  0.1327, 0.1210, 0.0000, 0.0077]
corr(pivot_3, waist_state[0]) = 0.733
corr(pivot_4, waist_state[2]) = 0.867
base nonzero fraction = [0.0021, 0.0013, 0.0003]   # vx, vy, yaw
```

即：`pivot_3/pivot_4` 很可能是腰 yaw/pitch 的目标（存在轴序/偏置差异），`pivot[0:3]` 是基座平移/转向，`height` 是基座高度。**OrganizeTools 的演示确实会移动基座、调整高度、改变躯干俯仰去够工具架；其他多数任务基座静止、姿态是任务级常数。**

**风险**：参考实现 `example_policy.py` 返回 `action.pivot = zeros(T,7)`。如果 pivot 是绝对目标，零意味着高度/姿态归零，可能灾难性；如果是增量/保持，零才中性。接口未写明。必须验证，默认采用 **Pivot Guard**（见 §4.4）。

## 2. 评分算术：成功率优先，步骤分只做 tie-break

### 2.1 总目标

```text
S = (1/32) Σ_t (1/10) Σ_{i=1}^{10} 1[episode t,i 成功]
tie-break: 步骤分（仅当 S 相同）；再 tie-break: 提交日期较早
```

推论：

1. **每个任务对总分的边际权重相同**（1/32）。不存在“某个任务更重要”；应按“每单位努力能提升多少成功率”排序，而不是按步骤分权重排序。
2. **步骤分只在成功率相同时起作用**。为了部分分牺牲成功率是负期望；但部分分仍是同分时的第二排序键，所以在不牺牲成功率的前提下，能多完成一步就多完成一步。
3. **终局放置仍是成功闸门**：32/32 任务的 `score_steps` 最后一步都是完成判定；任一前置步骤失败，终局无法完成。第 7 轮的“终局=闸门”成立；“终局=39.8% 分数”只是 tie-break 层面的次要理由。
4. **跨轴杠杆仍成立**：终局放置/插入/闭合在每个轴、每个任务都要发生；提升它，成功率的收益跨五轴，而不是只提升一个轴。

### 2.2 统计噪声

| 层级 | trial 数 | p=0.30 时 SE | 含义 |
|---|---:|---:|---|
| 总体 | 320 | 2.56pp | +3pp 只有 1.2 SE；+5pp 约 2 SE |
| 单任务 | 10 | 14.5pp | 任务级分辨率 10%；不要对单任务 1 次差异大惊小怪 |
| 单轴（32 任务合并） | 64 | 5.73pp | 轴级差异 5pp 仍可能是噪声 |
| 单任务单轴 | 2 | 32.4pp | 几乎不可用；不要用它做模型选择 |

因此：**用任务级配对比较 + bootstrap；目标 +5pp；不要追 1–2pp 的“提升”；不要用 2 个 trial 的轴级差异写结论。**

### 2.3 收益模型与敏感性

```text
ΔS ≈ f·ρ·q − p·α·c
p=0.30, f=0.70, α=0.05, c=0.30
```

| ρ \ q | 0.30 | 0.50 | 0.70 |
|---:|---:|---:|---:|
| 0.10 | +1.65pp | +3.05pp | +4.45pp |
| 0.20 | +3.75pp | +6.55pp | +9.35pp |
| 0.30 | +5.85pp | +10.05pp | +14.25pp |

（已扣除误触发损失 0.45pp。）**保守目标 +3–4pp，基准 +6.5pp，乐观 +10pp。** 如果调试槽显示 ρ<0.10 或 q<0.30，RECON 不值得继续，回退到 Pivot Guard + Compliance Governor。

### 2.4 时间预算

- 官方上限 180s；演示中位约 6s（HangCup），官方 169h/32k ≈ 19s 平均；长程任务更久。
- 恢复选项耗时估计：re-grasp 5–10s；re-align 3–8s；re-place 5–12s；re-insert 5–15s；re-localize 3–8s；step-reset 5–15s；abort <2s。
- 180s 内可承受 2–3 次恢复；长程任务（T16/T17/T31）上限 1–2 次。
- 触发必须留 `T_recover + ε`（ε≈5s）；剩余时间 <10s 时只允许快速选项（re-align/re-grasp）或 abort。

### 2.5 策略推论

1. **先提交一个稳定基线**：手册说同分时提交日期较早者靠前；若平台允许多个 entry，早提交可占 tie-break 优势。提交次数未写明，标“未核实”；若只允许一次，则不要浪费。
2. **任务分诊**：优先高可恢复性任务（T27/T10/T26/T20/T21/T25/T07/T32），不要先啃 T16/T19/T03。
3. **不要为 partial score 牺牲 success**：例如，为了完成第 3 步而冒险抓一个已经滑落的物体，可能把“已成功的部分分”变成“失败 + 更低步骤分”。
4. **真实榜单出现后重跑**：当前 29.7% 是占位；真实基线可能更高或更低。收益模型要重新校准。

### 4.2 EQUIL：五类平衡裕度

裕度统一写成 `m_i ∈ [0,1]`，越大越安全；失败 = 任一裕度跨过 0（或低于任务阈值）。

| 裕度 | 定义 | 估计方式 | 适用任务 | 失效回退 |
|---|---|---|---|---|
| 抓取 `m_g` | 夹爪-物体关系的稳定度 | 夹爪开度 vs 物体宽度（颜色/深度分割）；腕部光流相对速度；跟踪误差 | 全部 | 纯视觉滑落分类 |
| 支撑 `m_s` | 物体/堆叠重心投影到支撑多边形的归一化有符号距离 | 立体深度 + 颜色/实例分割 + 已知几何模板；堆叠时合成 CoM | T20/T21/T25/T27/T07/T03/T29 | 学习式 topple 分类 |
| 插入 `m_i` | 对齐/间隙/力余量 | 腕部相机估计插头-插座轴角/横向偏差；跟踪误差作力代理 | T10/T26/T32/T14/T12 | 动作/跟踪误差 only |
| 运动学 `m_k` | 关节限位/工作空间余量 | 关节角 vs 限位；EE 位姿 vs 可达域 | 全部 | 无 |
| 时间 `m_t` | 剩余预算 vs 预计完成时间 | 演示时长分位 + 当前步骤进度 | 全部 | 无 |

**支撑裕度公式**（刚体/堆叠）：

```text
CoM_xy = Σ_i m_i · c_i,xy / Σ_i m_i
m_s = signed_distance(CoM_xy, ∂SupportPolygon) / L_char
```

- `c_i` 是各物体/层的质心；`m_i` 可用类别先验或体积×密度估计；`L_char` 是物体特征长度（如碗直径）。
- 支撑多边形 = 最底层接触点的凸包；对堆叠，逐层检查“上层 CoM 是否落在下层支撑面内”。
- 透明物体（试管、注射器）深度不稳：回退到“夹爪-容器相对位姿 + 跟踪误差”，不算支撑多边形。
- 布料（毛巾）：没有刚性支撑多边形；只用 `m_g`、`m_t`、SSG 进度。

**异常分数**：

```text
a_t = || m_t − MDM(m_{t-1}, a_{t-1}, z_{t-1}) ||_Σ
```

即“观测裕度”与“正常动力学预测”的残差。滑落、卡死、被人移动、碰撞都会表现为残差尖峰；背景换色不会（因为裕度用几何/本体，不用全局外观）。

**Nuisance-invariance 训练**：

- 正样本对：同一 episode，换背景/光照/加干扰物/改物体颜色（外观变，物理不变）。
- 负样本：滑落、卡死、目标平移、遮挡、动作延迟（物理变）。
- 损失：对比学习 + 二分类“nuisance vs failure”；让表征对前者不变、对后者敏感。
- 评测：在背景/干扰物/位置轴上测误报率；在 human/滑落/卡死上测检测率。

### 4.3 MDM/TTU：裕度动力学与可恢复性

**输入**：最近 H 帧的 `m`、action chunk、SSG 步骤 embedding、语言 embedding、可选的 VLA 视觉 token。
**输出**：

- `m_{t+1..t+K}`（K=10–30 步）；
- TTU 的 10/50/90% 分位；
- 8 类失败模式 logits；
- `R_continue`（继续当前动作的成功概率）。

**训练标签**：

1. **正常动力学**：成功演示的 `(m_t, a_t) → m_{t+1}`，一步/多步 MSE。
2. **合成异常**：注入滑落/卡死/目标平移/遮挡/延迟，标签为失败模式 + “距失败帧的时间”。
3. **仿真反事实**：对 8 个关键任务，在仿真里恢复状态、分支 rollout，估计 `P(success | s, b)`；Kintsugi 式，但用于运行时 critic 而不是数据选择。
4. **弱标签**：真实数据上，用“物体仍在工作空间、夹爪仍持有、时间剩余”构造保守的可恢复性标签；只用于预训练，不用作最终校准。

**Conformal 校准**：

- 在 held-out 成功 episode 上计算 `a_t` 和 `TTU` 的分数；取经验分位数，使误触发率 ≤ α（如 5%）。
- 对 TTU 用 conformalized quantile regression，给出有限样本覆盖的下界。
- 触发阈值不是拍脑袋，而是“在成功数据上保证误报预算”。

**触发规则**：

```python
def should_intervene(m, ttu_q10, b, r_best):
    if b < T_recover[r_best] + EPS:      # 时间不够，选快速选项或 abort
        return FAST_ONLY
    if ttu_q10 < T_recover[r_best] + EPS and R_recover[r_best] > R_continue + DELTA:
        return True
    return False
```

**为什么是 TTU 而不是 failure probability**：failure probability 在失败前很久就可能很高（任务难），但状态仍可恢复；TTU 直接和“还剩多少时间/多少裕度”对齐，适合 180s 预算下的干预决策。Kintsugi 的非单调可恢复性支持这一点。

| re-place | 抬起→平移/旋转→慢放→稳定检查 | F4 | T20/T21/T25/T27 | 5–12s |
| re-insert | 柔顺搜索（小幅圆/螺旋）→力反馈回退→再插 | F5 | T10/T26/T32 | 5–15s |
| re-support | 支撑手移到稳定接触点，抵消操作力 | F5/F6 | T10/T26/T14/T19 | 3–8s |
| step-reset | 回到当前步骤的安全起点，重试 | F8 | T16/T17/T31 | 5–15s |
| abort | 安全释放/停止，避免更糟 | 任意不可恢复 | — | <2s |

**实现**：每个选项是一个短 prompt/token（例如 `"recover: re-grasp; step=2; target=bowl2"`）+ 可选确定性控制器。同一 checkpoint 通过 recovery token 进入对应模式；不加载第二个模型。训练数据来自 NRB、合成失败、仿真恢复片段、成功演示里的自然重试段。

**Router**：

```text
r* = argmax_r R̂(s, b, r)
R̂ 由 MDM 在“选项 r 的预期动作序列”下 rollout 得到，
或用失败模式分类器 + 选项成功率查表（冷启动）。
```

冷启动阶段用规则表（模式→选项），有数据后切换到学习 router；两者都在同一 checkpoint/确定性代码内。

### 4.6 Compliance Governor：无力传感器的接触柔顺

```python
e = || q_cmd - q_obs ||  # 或 EE pose error，归一化
if e > e_high and progress_low:
    v_cmd *= 0.5                 # 降速
    back_off(2-5mm)              # 回退
    search_circle(radius=1-3mm)  # 小范围搜索
    approach_slowly()
elif e < e_low and progress_ok:
    continue()
else:
    hold_or_re_grip()
```

- 适用：T10/T26/T32/T14/T12/T19/T31。
- 证据：Current as Touch（电流→compliance）、InsertAnything（力信号）、Blind Dexterity（本体接触通道）、Nefzer（proprioception 早期失败）。
- 风险：跟踪误差也受自由空间动力学影响；按速度/加速度归一化，分任务校准；不要过度反应。
- 这是 RECON 的一个“低层恢复选项”，也可以独立于 TTU 使用。

### 4.7 单模型合规

- **一个 checkpoint**：WLA-1.0-Base 主干 + LoRA/action expert + SSG 谓词头 + margin/TTU 头 + 失败模式头 + recovery token embedding。所有任务共享权重，没有 per-task LoRA/模型。
- **确定性代码**：EQUIL 几何、Pivot Guard、Compliance Governor、conformal 阈值、规则 router。
- **不调用外部学习型 detector**：VLA-FAIL/ActProbe/RC-NF 只作为离线基线；推理时不用。
- **感知**：优先用立体深度 + 颜色/实例分割 + 同一 checkpoint 的视觉特征；SAM/DepthAnything 只用于离线标注，不进推理。若规则允许，再考虑。
- **模型卡**：列出所有组件、数据来源、确定性模块、单 checkpoint 哈希；审计时能逐项说明。

### 6.2 指标

- **主**：32 任务总平均成功率；分任务/分轴成功率。
- **次**：步骤分（tie-break）；干预次数/时间开销。
- **监控**：AUROC、AUCPDT、检测提前量（占 episode 比例）、成功 episode 误报率、失败 episode 漏报率。
- **恢复**：恢复成功率、恢复后剩余时间、恢复后再次失败率。
- **平衡**：堆叠倒落率、支撑裕度校准误差、插入成功率、跟踪误差。
- **跨任务**：leave-one-task-out AUROC/恢复成功率。
- **工程**：p99 延迟、显存、吞吐、N 端口并发。

### 6.3 三级评测

1. **离线（每天）**：held-out 成功演示上的裕度分布、异常残差、nuisance 误报；leave-one-task-out。
2. **仿真（每周）**：8 任务反事实恢复；TTU 校准；ROL 选项成功率；消融。
3. **真机调试槽（版本门）**：T27（叠碗）+ T10（插头）优先；脚本化 human 备注（拿走第二个碗、拔起插头、移动插排）；测误报/恢复/时间。每个大版本最多 1 槽。
4. **计分跑**：W7 中期、W8 终期；若只允许 1 次，W8 唯一一次。

### 6.4 消融

- 监控信号：EQUIL 裕度 vs 动作 TCE vs VLA 特征 vs 状态 flow。
- 触发：TTU vs failure probability vs 固定阈值。
- 训练：nuisance-aware vs 朴素异常检测。
- 跨任务：共享头 vs 任务条件头 vs 任务族条件头。
- 恢复：全选项 vs 单选项 vs 无恢复。
- 安全：Pivot Guard on/off；零 pivot vs 名义 pivot。
- 接触：Compliance Governor on/off。
- 姿态：PAR on/off。
- 校准：conformal vs 固定阈值。

### 6.5 统计计划

- 320 trial；任务级配对（同任务、同轴、同种子）；bootstrap 95% CI。
- 目标 +5pp；若 CI 跨 0，不上线。
- 轴级分析合并 32 任务（64 trial/轴），不要单任务单轴下结论。
- 记录每次干预的因果链（触发信号→选项→结果），做失败复盘。

### 6.6 Go/No-Go

| 门 | 条件 | 不过则 |
|---|---|---|
| G1 Pivot 语义 | 调试槽确认名义 pivot 不导致跌倒/超时 | 改用零/保持，记录 |
| G2 裕度监控 | nuisance 误报 <5%，leave-one-task-out AUROC >0.65 | 回退到动作+本体信号 |
| G3 TTU 校准 | 覆盖误差 <20%，误触发 <10% | 改用固定阈值 + SVL |

### 7.1 I14 EQUIL（新/押注）

- **动机**：失败不是“画面异常”，而是抓取/支撑/插入/运动/时间裕度的耗尽；裕度是跨任务共享的物理量。
- **差异**：通用异常检测用像素/特征重构；我们用可解释的物理裕度 + 残差。RC-NF 用 robot/object state flow，但仍以任务为条件；我们显式定义五类裕度并做 nuisance 不变性。
- **可行性**：立体相机 + 颜色/实例分割 + 已知几何；关节/EE/夹爪直接可读；透明/布料有回退。
- **资源**：离线几何管线 3–5 天；无需新数据；无需外部模型（可用经典 CV）。
- **步骤**：先做 T27/T20/T21/T10/T26 五个任务；标定裕度阈值；再做 nuisance 对；最后扩到 32 任务。
- **风险**：透明物体深度不稳；支撑多边形对非刚体无效；分割错误导致误报。回退：只用抓取/时间/进度裕度。
- **状态**：押注。

### 7.2 I15 MDM/TTU（新/押注）

- **动机**：检测器回答“会不会失败”，但比赛要“还能不能救”；TTU 直接对齐 180s 预算与可恢复性。
- **差异**：VLA-FAIL/ActProbe/RC-NF 输出 failure score；我们输出 TTU 分位 + 失败模式 + R_continue；Kintsugi 用可恢复性选训练数据，我们用于运行时决策。
- **可行性**：MDM 是小型辅助头；训练标签来自成功演示 + 合成异常 + 8 任务仿真反事实；conformal 校准有现成方法。
- **资源**：8×H100 1–2 天/轮；仿真 3–7 天；调试槽 2 次。
- **步骤**：正常动力学→合成异常→仿真反事实→conformal→调试槽。
- **风险**：没有失败数据导致 TTU 标签偏差；仿真-现实 gap；leave-one-task-out 不达标。回退：固定阈值 + SVL。
- **状态**：押注。

### 7.3 I16 ROL（新/押注）

- **动机**：检测到失败后，需要有“可执行的恢复动作”；32 任务共享失败物理，恢复选项可共享。
- **差异**：VLA-Pro/Decompose & Recompose 共享技能，但用 per-task LoRA/技能库；我们用同一 checkpoint 的 recovery token + 确定性控制器，合规。
- **可行性**：8 个选项都是短动作序列；NRB 提供剧本；仿真/合成提供训练对；规则 router 可冷启动。
- **资源**：训练数据 3–5k 段；1 人月工程；调试槽验证。
- **步骤**：规则 router→仿真选项成功率→学习 router→真机。
- **风险**：恢复动作本身失败/超时；选项间冲突；单模型 token 条件训练不充分。回退：只保留 re-grasp/re-place/re-align 三个。
- **状态**：押注。

### 7.4 I17 Pivot Guard（新/必做）

- **动机**：数据表明 pivot 含躯干姿态/高度/基座；参考实现返回零；语义未文档化。零可能是灾难。
- **差异**：没人会注意这个 shared 键；这是接口层的“免费”风险消除。
- **可行性**：从数据集算每任务名义 pivot；限幅；reset 初始化；一次调试槽验证。
- **资源**：1 人周；无需训练。
- **步骤**：全量重算 32 任务名义 pivot→本地测试→调试槽“名义 vs 零”→默认开启。
- **风险**：语义是增量导致名义值重复叠加；需要读 controller/本地测试；若不确定，用“保持当前”而非绝对。
- **状态**：必做（所有版本默认）。

### 7.5 I18 PAR（新/可选）

- **动机**：OrganizeTools 演示会移动基座/调高度/改躯干；位置泛化可能把目标移出名义可达域；小偏差姿态可扩展 reach。
- **差异**：不是激进全身平衡，而是在名义 pivot 附近的有界偏差；只在演示支持的任务/条件下用。
- **可行性**：pivot 通道可控制；有 T15 的基座运动示范；可用几何 reach 裕度触发。
- **资源**：1–2 人周；调试槽 1 次。
- **步骤**：reach 裕度→小偏差策略→T15/T08/T21 测试→默认关闭，只在触发时开。
- **风险**：OOD 姿态导致跌倒/超时；收益只在位置轴 2/10 trial；可能不值得。**默认不做，除非 G4 后有余力。**
- **状态**：可选。

### 7.6 I19 Compliance Governor（新/中优先）

- **动机**：插入/拧盖/拉链失败常是卡死/打滑；无力传感器，但跟踪误差可作代理。
- **差异**：把“力控”降级成“位置跟踪误差外环”，不需要新硬件；与 RECON 的 re-insert 选项互补。
- **可行性**：只用关节位置/EE 跟踪误差；确定性控制器；可独立于学习。
- **资源**：1 人周；调试槽 T10/T26。
- **步骤**：误差归一化→回退/搜索→插入测试→默认开启（仅接触任务）。
- **风险**：自由空间误差误判；参数敏感；可能拖慢成功 episode。用速度归一化 + 任务阈值。
- **状态**：中优先。

### 7.7 I20 NMR checkpoint 选择（新/低成本）

- **动机**：背景轴是 nuisance；NMR 可预测模型对任务无关特征的依赖。
- **差异**：不用改训练，只做 checkpoint 选择/诊断；比盲目早停更 aligned。
- **可行性**：离线 interventional masking；子集帧/任务；成本中等。
- **资源**：1 人周；离线 GPU。
- **步骤**：选 8 任务×100 帧→算 NMR→与背景轴成功率相关→作为选择指标。
- **风险**：NMR 计算贵；与成功率相关性不一定强。作为辅助，不阻塞主线。
- **状态**：低成本可选。

### 7.8 I21 任务可恢复性分诊（新/策略）

- **动机**：320 trial 噪声大；把火力放在“救得回来”的任务上，收益/努力最高。
- **差异**：不是按步骤分/难度排序，而是按 `失败率 × 可恢复性 × 可检测性 / 努力` 排序。
- **可行性**：用任务语义 + 调试槽/仿真估 ρ/q；先做高可恢复性 8 任务。
- **资源**：分析 1 人周。
- **步骤**：先验表→仿真校准→调试槽→更新。
- **风险**：先验错；低可恢复性任务被忽视导致总分损失。每轮重排。
- **状态**：策略。

### 7.9 已砍/降级清单

- 通用黑箱异常检测器（会被背景变化误报）→ 砍，改为 nuisance-invariant 裕度。
- 视频 world model 进主路径（Foresight/DreamZero 类）→ 砍，改为裕度动力学。
- per-task LoRA/多个模型 → 砍，单模型合规。
- 全任务主动移基座 → 砍，只在 T15/PAR 受控实验。
- 全 32 任务高保真孪生 → 砍，只做 8 个关键任务。
- 运行时仿真/MPC、仿真 RL、布料/拉链/透明全物理、WMA-0 进主路径 → 砍。

## 附录 C：伪代码

### C.1 EQUIL 裕度

```python
def equil(obs, step, task):
    m_g = grasp_margin(obs)          # gripper width, wrist flow, tracking error
    m_s = support_margin(obs)        # stereo depth + masks + CoM/support polygon
    m_i = insertion_margin(obs)      # wrist alignment + tracking error
    m_k = kinematic_margin(obs)      # joint limits / reach
    m_t = time_margin(obs, step)     # remaining budget vs demo percentile
    return softmin([m_g, m_s, m_i, m_k, m_t])
```

### C.2 TTU 触发

```python
def recon_step(obs, step, budget, task):
    m = equil(obs, step, task)
    ttu_q10, mode, r_cont = mdm.predict(m_history, action_chunk, step, task)
    if budget < 10.0:
        options = FAST_OPTIONS
    else:
        options = ALL_OPTIONS
    r_best = max(options, key=lambda r: recoverability(obs, budget, r))
    if ttu_q10 < T_recover[r_best] + 5.0 and recoverability(obs, budget, r_best) > r_cont + 0.1:
        return recovery_token(r_best)
    return None
```

def pivot_action(task, t):

def compliance_adjust(action, q_obs, progress):
    e = norm(action.joint - q_obs)
    if e > E_HIGH and progress < P_LOW:
