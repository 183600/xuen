# 第 1 轮 · TASC：把「语言」变成任务索引，把「技能」变成共享货币，把「延迟」变成执行预算

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。
>
> 这是新灵感循环的第 1 轮，承接上一循环第 12 轮的 **CHUNK-SERVO**。我不推倒它，而是把它从「控制层」继续往上顶一层：上一轮解决「最后 3 厘米怎么闭环」，这一轮解决「闭环之前，模型怎么知道自己在做哪个任务、该调用哪种技能、以及有多少时间可以想」。三个灵感词是「推理延迟」「多语言支持」「跨任务泛化」。

## 0. 先给结论：榜首不到 30%，缺的不只是闭环，而是「任务锚点 + 技能共享 + 延迟预算」三件事

截至 2026-10-31，我通过 `r.jina.ai` 只读代理读取了排行榜 JSON 和页面（本机直连被 EdgeOne 拦截，返回 567）：8 个模型、榜首 MolmoAct2 **29.7%**、WALL-OSS-0.5 **28.5%**、DreamZero **27.9%**、Spirit-v1.5 **25.9%**、DM0 **23.5%**、π0.5 **22.8%**、GigaBrain-0 **22.6%**、GR00T N1.5 **20.5%**。数字与 2026-10-28 的快照一致，说明至少通过 reader 仍能拿到同一份榜单；但详情页 32 个任务视频仍然全部是「测试视频占位」，且 `step_score ~ success_rate` 的回归 R² 仍在 0.9999996–0.9999999，斜率 1.305–1.371。**结论：29.7% 可以当「难度信号」，不能当「任务难度表」或「失败分布」。**

上一轮的判断是：所有模型共享同一个执行瓶颈——1 秒开环 chunk + 远程 RTT，最后 3 厘米没有闭环。这个判断我保留。但这一轮我把 32 个数据集的任务指令全部读了一遍，发现了一个上一轮没有充分利用的结构：

- 每个任务不是一条指令，而是 **5 条英文释义**，32×5 = **160 条**；训练代码 `random.choice(item["task"].split("@"))` 每次随机抽一条。也就是说，官方 WLA 的微调数据本身已经做了「同义改写增强」。
- 但官方 WLA server 的 `unnorm_key` **不会从语言推断**：`_resolve_unnorm_key` 只看请求里的 `unnorm_key` 或启动参数 `--unnorm_key`，否则报错。挑战赛 API 又**没有** `unnorm_key` 字段，只有 `observation.language`。这意味着：**语言在接口层是「有字段、没路由」的**。如果 32 个任务的动作归一化统计不同，adapter 不把语言映射到正确的 `unnorm_key`，动作尺度就会错。
- 我把 32 个任务的 160 条释义做词袋 Jaccard，再把 32 个任务的 action/state 统计做 z-score 余弦，两者相关系数只有 **r = -0.033**。语言相似的任务（比如插网线 vs 拔网线）运动并不相似；运动相似的任务（比如装铅笔盒 vs 移除图钉）语言并不相似。**「用语言嵌入找相似任务」这条路，至少不能直接用。**

所以本轮的押注是 **TASC（Task-Anchored Skill Cascade，任务锚定技能级联）**：

> 用 160 条释义学习一个**语言无关的任务锚点**（task anchor），用锚点选择 `unnorm_key`、任务嵌入和技能权重；用 33k 成功演示构建一个**跨任务技能缓存**，把「相对末端轨迹 + 腕部目标图」作为快速先验；用**技能因子化**的动作头把 32 个任务压到 K 个共享技能基上；用**延迟感知的双频执行器**把 VLA 的 1 秒规划、167ms 伺服和网络 RTT 放进同一个预算。最终仍然是**一个学习模型（WLA）+ 一个确定性路由器 + 一个非参数技能缓存 + 一个确定性伺服**，不违反单模型规则。

三个灵感词怎么落地：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **推理延迟** | LADE：VLA 后台 30 步规划，`get_action` 只走「缓存/检索 + 5 步伺服」的快路径；`action_chunk_size` 在提交前扫，不在运行时改；p99 延迟和抖动当一等指标 | 不承诺运行时改 chunk；不做 30Hz 广域网伺服；不让 `get_action` 阻塞等 VLA |
| **多语言支持** | TAR：160 条英文释义 + 中文回译/词典，统一映射到 32 个结构化锚点；锚点选 `unnorm_key`、任务嵌入和技能权重 | 不把「中文」当主赛道；不训练第二个翻译模型上线；不假设评测一定用中文 |
| **跨任务泛化** | SKF + XTSC：任务嵌入 = 共享技能基的稀疏组合；技能缓存允许从其他任务检索相对轨迹；先验只做伺服参考，不直接输出动作 | 不做逐任务策略；不做第二个学习残差；不把语言相似当技能相似 |

一句话：**语言不是 prompt，是索引；技能不是任务，是共享基；延迟不是平均值，是 p99 预算。**

## 1. 本轮新核实/修正的事实（只列会改变方案的）

### 1.1 榜单：仍然在线，但仍是「预览」；29.7% 可复核，任务级分数不可用

我通过 `r.jina.ai` 抓取（本机直连被 EdgeOne 拦截，返回 567；这是访问方式问题，不是榜单下线）：

- 排行榜页：8/8 个模型，MolmoAct2 29.7% / 39.0，WALL-OSS-0.5 28.5% / 38.9，DreamZero 27.9% / 37.9，Spirit-v1.5 25.9% / 34.4，DM0 23.5% / 31.7，π0.5 22.8% / 30.6，GigaBrain-0 22.6% / 29.5，GR00T N1.5 20.5% / 28.1。
- 排行榜 JSON 的 `generated_from` 仍是 `gen_leaderboard.py`；对 8 个模型 ×32 任务做 `step_score ~ success_rate` 回归，R² = 0.9999996–0.9999999，斜率 1.305–1.371，截距约 0。**步骤分不是独立测量，是成功率的线性缩放。**
- 8 个模型的 32 维任务成功率两两相关，平均 off-diagonal **r = 0.0975**；如果任务难度是真实的，不同模型在同一任务上应该正相关。任务级信号很弱，至少不能当难度表。
- 每任务只有 10 次 trial，但成功率出现 27.29%、27.85%、38.43% 等非 10% 整数倍；真实 10 次只能是 0/10…10/10。
- 详情页 32 个任务视频全部是「测试视频占位，后续可替换为真实视频文件」。

我进一步算了两个量：

- **Oracle 逐任务选模型**（每个任务取 8 个模型里的最高成功率，再平均）= **33.96%**，只比榜首 29.7% 高 **4.26pp**。也就是说，即使允许「按任务挑模型」——规则不允许——上限也不到 34%。**瓶颈不是模型选择，是共享的执行/接触问题。**
- 模型内任务成功率的标准差平均 **5.55pp**，模型间平均成功率的标准差只有 **3.09pp**。任务级波动大于模型级差异，但跨模型任务相关又接近 0，说明任务级数字更像「围绕模型均值的噪声」，不是「任务难度」。

**对方案的约束**：不从榜单任务排名里挖「哪些任务难」；只从公开模型家族的技术路线和官方数据/规则里挖。29.7% 作为「30% 天花板」的难度信号保留。

### 1.2 API：v2 固定 chunk；`action_chunk_size` 不能运行时改；语言字段可用但需要路由

提交模板当前是 **v2**（commit `edd0a1c9`，2026-08-21）：`metadata` 用 `obs_delta_indices`（选观测 + 时序叠帧）和 `image_resize`，不是旧版的 `data_keys`/`obs_chunk_size`。网上仍能搜到旧版文档，必须以 main 分支为准。

关键事实：

- 观测：四路 RGB 480×640（`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`）、双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、`observation.language` 单字符串。
- 动作：`joint` 或 `ee` 互斥；共享 `left_gripper`、`right_gripper`、`pivot[7]`；`ee` 模式是**绝对目标位姿** xyz+rpy。
- `action_chunk_size` 是 metadata 里的固定整数；evaluator 按 chunk 顺序执行，chunk 内没有新观测，也没有打断机制。**它是提交前参数，不是运行时参数。** 上一轮说「chunk size 是控制参数」——更准确的说法是「提交时的控制参数」；运行时能改的是内部 plan 刷新节奏，不是 API 返回长度。
- `observation.language` 是单字符串、全程不变、无时间轴；README 示例是 `"move the block to the target position."`。
- 评测跨 N 台机器人，提交须从 8765 起暴露 N 个连续端口；每端口独立 `reset()`，状态隔离。
- README §6 明确：评测端逐调用记录 **latency 和 variability**，并可能和结果一起展示；要求「保持交互延迟平滑稳定，返回动作尽量无异常」。**延迟不只是性能，是可信度指标。**

**对方案的约束**：TASC 的 `get_action` 快路径必须在几十毫秒内返回；VLA 只能在后台线程里跑，不能阻塞；chunk 大小要在单任务通道里扫，不能运行时变。

### 1.3 数据：33,276 eps / 169.28 h / 160 条释义；英语单语；无 subtask 标签

32 个 HF 数据集的 `meta/info.json` 逐份读取（2026-10-31）：

| 项 | 数值 |
|---|---:|
| episodes | **33,276** |
| frames | **18,282,246** |
| 时长 | **169.28 h**（30 fps） |
| 任务数 | 32 |
| 指令释义 | **160 条**（每任务 5 条，`@` 分隔） |
| 单任务 episodes | 969–1,533 |
| 单任务时长 | 1.8–11.1 h |
| 语言 | **英语单语**（没有中文指令） |
| subtask 标签 | **没有**（`info.features` 只有 `task_index`，没有 `subtask_index`/`subtasks.parquet`） |

`meta/tasks.parquet` 每份只有 1 行，`task` 字段是 5 条释义用 `@` 拼接。例如 HangCup：

```text
Hang the cup on the marked spot on the cup rack.@Hang the cup on the marked position of the cup rack.@Hook the cup onto the marked spot of the cup rack.@Hang the cup at the marked place on the cup rack.@Hook the cup on the marked position on the cup rack.
```

WLA 的 `single_source_dataset.py` 第 515 行：

```python
task = random.choice(item.get("task", "").split("@")) if item.get("task") else ""
```

所以**官方微调已经在做 5 选 1 的释义增强**。这带来两个推论：

1. 单纯「再做过改写增强」不是差异化，baseline 已经有了；
2. 真正没被利用的是：**把释义映射成一个结构化任务锚点，并用锚点去做 `unnorm_key`、任务嵌入、技能权重的路由**。

160 条释义的词长 6–21 词，平均 10.3 词；动词高度泛化（set 16、place 15、put 14、lay 12），语义主要在**对象 + 受器 + 约束**（杯架、网口、红绿蓝顺序、从右到左、锁、拉链）。这意味着「动词分类器」不可靠，「对象/受器/约束锚点」更可靠。

### 1.4 WLA：6B / 30 步 / 4 步去噪；语言可用，但 `unnorm_key` 不会从语言推断

官方 `unifolm-wla`（2026-10-31 复核）：

- **6B** 参数，约 **2,500 h** 真机数据，**64** 个任务；Base 权重 + 微调代码 + LoRA 代码已开源（2026-09-28）。
- 动作专家默认 `action_horizon=30`、`num_inference_timesteps=4`；DiT-L，16 层，hidden 1024；VLM 冻结（`freeze_modules: qwen_vl_interface`），只训 DiT + robot-state projector；单张 **24GB** GPU 可微调。
- 动作空间 54 维，状态 60 维；EE 是相对当前 EE 的 xyz+rotvec，服务端 compose 成绝对位姿。
- 模型服务器 `action_server_wbc_msgpack_unitree.py`：
  - `instruction = obs.get("instruction") or obs.get("task") or self.instruction`，然后 `example["lang"] = instruction`。**语言不是固定 prompt，只要 adapter 传进去就会用。**
  - `_resolve_unnorm_key(obs)` 只看 `obs["unnorm_key"]` 或 `--unnorm_key`，**不会从 `instruction` 推断**；多数据集 checkpoint 必须显式传 key，否则报错。
  - 观测键是 `observation.state.left_ee_6d`（xyz+rot6d 9 维）、`right_ee_6d`、gripper、lower_body；挑战赛给的是 xyz+rpy 6 维，adapter 必须做 rpy→rot6d。
  - 返回 `action.left_ee_rpy`、`action.right_ee_rpy`、gripper、lower_body、base_command、pivot；挑战赛 `ee` 模式只要 2×6 + 2×1 + 7 pivot，需要裁剪/映射。

**战略结论**：不要从零训 6B。用官方 WLA Base 做 action-head 微调；把省下的算力投到「任务锚点 + 技能因子 + 延迟调度」。但必须先解决两个接口缺口：

1. **语言 → `unnorm_key`**：32 个任务的动作统计不同，key 错了动作尺度就错；
2. **rpy ↔ rot6d / 54D ↔ 21D**：位姿约定和动作切片必须用 `example_env.py` + 单任务通道验证。

### 1.5 负结果：语言相似 ≠ 运动相似（r = -0.033），所以「语言嵌入找技能」不能直接用

我把 32 个任务的 160 条释义做词袋（去停用词、简单词干化），两两算 Jaccard；再把每个任务的 `action.left_arm/right_arm/left_gripper/right_gripper/pivot` 和 `observation.state.left_arm/right_arm` 的 mean+std 拼成向量，逐维 z-score 后两两算余弦。结果：

- **Pearson r = -0.033**（语言 Jaccard vs 运动余弦）。
- 语言最相似的对：DisconnectEthernet ↔ PlugInEthernet 0.556；ArrangePlates ↔ ColorArrangement 0.500；OrganizePencilCase ↔ PackBag 0.450。
- 运动最相似的对：OrganizePencilCase ↔ RemovePinnedNote 0.589；ColorArrangement ↔ OrganizeStationery 0.583；PackPhone ↔ PlacePhotoFrame 0.579；FruitSorting ↔ PaperCupStacking 0.574；HangCup ↔ FruitCollection 0.521。

运动最相似的对里，很多语义上并不相关。这说明：**整条轨迹的全局运动统计不是「技能」**；它混入了工作空间、手臂偏好、任务时长。真正的技能相似性必须来自**接触相位/相对轨迹**，不能来自语言嵌入，也不能来自全局动作统计。

这个负结果直接修剪了一个诱人的想法：「用多语言文本嵌入做跨任务检索」。文本嵌入可以做**任务锚点**（选任务/选归一化），但不能做**技能检索**（选运动先验）。技能检索要用相对末端轨迹 + 接触相位 + 视觉目标。

### 1.6 头部方案的做法与瓶颈：四种路线，同一个「没有任务锚点/技能共享」

| 模型家族 | 公开路线 | 优势 | 与本轮相关的瓶颈 |
|---|---|---|---|
| **MolmoAct2** | Ai2 的 action reasoning model；Molmo 2-ER + 专用 action expert + adaptive depth reasoning；强调 3D 空间推理、推理加速、无 per-task 微调 | 3D/空间语义强；推理快；双臂 | 端到端通才，没有显式任务锚点/技能基；最后接触仍靠开环 chunk |
| **WALL-OSS-0.5** | X Square 的 4B VLA（3B VLM + action expert）；公开材料称 15 个真机任务 60.5% average task progress | 预训练直接可用；progress 高 | progress ≠ success；4B 实时性；任务条件靠语言，缺显式路由 |
| **DreamZero** | 14B Wan2.1 video-diffusion world-action model；预测未来视频再出动作 | 长程预测/规划 | 14B 推理重；世界模型不直接解决毫米级接触；1 秒 chunk 更危险 |
| **π0.5** | Physical Intelligence 的开放世界泛化 VLA | 语义/新场景泛化 | 接触密集任务精度；远程部署延迟 |
| **GigaBrain-0** | 世界模型生成数据 + VLA | 数据效率/泛化 | 生成数据物理保真度；最后 3 厘米 |
| **GR00T N1.5** | NVIDIA 通用人形 VLA | 生态/embodiment | 任务特定精度；数据覆盖 |

共同点：都是**端到端通才**，都输出 action chunk，chunk 内不看新图；没有一家把「32 个固定任务 + 5 条释义 + 5 类泛化」这个结构显式用起来。它们把语言当条件，我们把语言当**索引**；它们把技能隐式学在权重里，我们把技能做成**共享基 + 可检索先验**；它们把延迟当工程问题，我们把延迟当**可信度指标 + 调度约束**。

## 2. 诊断：三个缺口叠在一起

```text
t0: 观测 + language → 语言编码 → VLA 推理（6B，100–400ms）→ 30 步 chunk
t0+0.1s: evaluator 开始执行 chunk
t0+0.1s … t0+1.1s: 机器人开环执行 30 步
        ↑ 接触/滑移/人移动物体都发生在这一段
t0+1.1s: 才看到下一帧 → 已经晚了
```

三个缺口：

1. **语言缺口**：160 条释义已经在数据里，但线上没有一个「语言 → 任务锚点 → `unnorm_key`/技能」的路由；WLA server 的 `unnorm_key` 不会从语言推断。语言字段存在，功能上却是「哑」的。
2. **技能缺口**：32 个任务共享插入、挂、叠、拉链、拧、倒、折等接触原语，但端到端模型没有显式共享基；语言相似 ≠ 运动相似，所以不能靠文本嵌入做技能迁移。
3. **延迟缺口**：6B + 远程 API，chunk 固定，RTT 未知；评测端记录 latency/variability，抖动本身可能损害可信度。上一轮的 5 步伺服解决了「反馈周期」，但没有解决「VLA 迟到时快路径用什么」——现在用**技能缓存**补上。

## 3. 方法：TASC 的四层

### 3.1 总架构

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
        ┌──────────────────────────────────────────────────┐
        │  Per-port TASC PolicyService (CPU)               │
        │  ├─ TAR: language → task anchor → unnorm_key     │
        │  ├─ SKF: task anchor → skill weights → DiT cond. │
        │  ├─ XTSC: anchor + obs → retrieved skill prior   │
        │  ├─ LADE: plan buffer + deadline scheduler       │
        │  ├─ SERVO: 5-step visual/relative correction     │
        │  └─ ADAPTER: WLA 54D → API 21D; rpy↔rot6d        │
        └──────────────┬───────────────────────────────────┘
                       │ async, batched, per-port state
                       ▼
        ┌──────────────────────────────────────────────────┐
        │  Shared WLA server (GPU, one checkpoint)         │
        │  frozen Qwen3-VL + DiT action head (30-step)     │
        │  + skill-factorized task conditioning            │
        └──────────────────────────────────────────────────┘
```

四层：

1. **TAR（Task Anchor Router）**：语言 → 结构化锚点 → `unnorm_key` + 任务嵌入 + 技能权重。
2. **SKF（Skill-Factorized action head）**：任务嵌入 = K 个共享技能基的稀疏组合；DiT 通过 AdaGN/FiLM 接收任务嵌入。
3. **XTSC（Cross-Task Skill Cache）**：33k 演示 → 接触相位分段 → 相对末端轨迹库；在线检索跨任务先验，供伺服参考。
4. **LADE（Latency-Aware Dual-frequency Executor）**：VLA 30 步规划后台跑；`get_action` 快路径 = 检索 + 5 步伺服；plan 过期/迟到有回退；p99 和抖动监控。

### 3.2 TAR：语言不是 prompt，是索引

锚点 schema：

```python
anchor = {
    "task_id": 0,                    # 0..31
    "verb": "hang",                  # 软特征，不硬判
    "object": "cup",
    "receptacle": "cup_rack",
    "constraints": ["marked_spot"],  # 颜色顺序/左右顺序/锁/拉链...
    "skill_weights": {"reach":0.1, "grasp":0.2, "hang":0.7},
    "unnorm_key": "G1_Dex1_HangCup", # 或合并 key
}
```

离线：

- 用 32 个任务名 + 160 条释义，人工/规则抽取 `object`、`receptacle`、`constraints`；
- 建同义词表：hang/hook、plug/insert/connect、unplug/disconnect/detach、unlock/unfasten/release、fold/crease、stack/pile/layer…；
- 建中文词典（杯子/杯架、网线/网口、拉链、锁、药瓶、试管架、工具箱…），把 160 条释义回译成中文，作为**离线增强**；
- 用 160 条英文 + 中文回译构建一个**确定性评分器**（关键词/模糊匹配），或直接用同一 WLA checkpoint 的文本编码器做最近邻（C3 合规）；不加载第二个学习模型上线。

在线：

```text
1. 归一化语言（小写、去标点、同义词替换）
2. 精确匹配 160 条释义 → anchor
3. 否则关键词/模糊匹配 object+receptacle+constraint → anchor + confidence
4. 否则用 VLM 文本编码器在 160 条锚点描述里做最近邻（同一 checkpoint）
5. confidence < θ → 返回 task-agnostic anchor，只用语言条件，不路由 unnorm_key/技能
```

输出：`task_id`、`unnorm_key`、`skill_weights`、`confidence`。

**与现有方案的差异**：baseline 把语言当 VLA 的文本条件；TAR 把语言当**路由键**，同时解决 `unnorm_key` 缺口和技能选择。**多语言支持**不是主赛道，而是 TAR 的自然副产品：中文/英文/改写都映射到同一个锚点。

### 3.3 SKF：任务嵌入 = 共享技能基的稀疏组合

设 K 个技能基嵌入 `E = [e_1, ..., e_K] ∈ R^{K×D}`，32 个任务的任务-技能权重 `W ∈ R^{32×K}`（稀疏/非负）。任务嵌入：

```math
e_{\text{task}}(t) = \sum_{k=1}^{K} W_{t,k}\, e_k .
```

DiT 的 AdaGN 条件从 `(diffusion timestep embedding)` 扩展为 `(timestep embedding + e_task)`；或把 `e_task` 拼到 robot-state projector 的输入。参数量：K×D + 32×K，K=12、D=256 时约 3k 参数，可忽略。

初始化：

- `W` 用任务释义的动词/对象先验初始化（plug→insert、hang→hang、stack→stack、zip→zip、pour→pour、fold→fold、unlock→rotate、sort→place…）；
- 训练时让 `W` 和 `E` 端到端学习，加稀疏/非负约束；
- 技能基共享 → 跨任务迁移；任务权重稀疏 → 任务特化。

消融：

| 变体 | 条件 | 假设 |
|---|---|---|
| A | 无任务嵌入（语言-only，baseline WLA） | 基线 |
| B | 32 个独立任务嵌入 | 任务特化，但小数据任务易过拟合 |
| C | K 个共享技能基 + 稀疏 W | 共享正则，跨任务更好 |
| D | C + XTSC 检索先验 | 技能先验 + 几何先验 |

如果 C 不优于 B，说明技能基没有共享价值，砍掉；如果 C 不优于 A，说明语言条件已经足够，SKF 降级为可选。

### 3.4 XTSC：跨任务技能缓存，检索的是「相对轨迹」不是「任务」

离线：

```text
for each episode:
    T_ee(t), g(t) = state/action
    phases = change_point(T_ee velocity, angular velocity, g)
    for each phase:
        T_end = T_ee(phase.end)          # 或估计的受器位姿
        rel(t) = T_end^{-1} T_ee(t)      # 相对末端轨迹
        rel_resampled = resample(rel, L=32)
        I_wrist_start/end = wrist images
        index.add(anchor, phase, rel_resampled, g, I_wrist, quality)
```

在线：

```text
1. 用 TAR 的 anchor 过滤候选（同任务优先；跨任务需同技能/同受器几何）
2. 用当前 EE 相对目标的轨迹前缀做 DTW/欧氏检索 top-k
3. 用腕部图 ORB/颜色/边缘做视觉重排
4. 用数字孪生/IK 做运动学可行性重排（关节限位、碰撞、可达）
5. 输出参考轨迹 rel*，变换到当前 base 系，作为伺服参考
```

关键：**缓存只提供参考，不直接输出动作**。动作仍由 VLA 的 action head 产生，伺服在 `±δ` 内修正。这样单模型合规，检索不是第二个策略。

跨任务实验（leave-one-task-out）：

- 对每个任务，把它自己的演示从缓存里移除，只从其他 31 个任务检索；
- 指标：top-5 的 IK 可行率、DTW 距离、仿真/真机成功率；
- 如果跨任务检索不如「只用 VLA」，砍掉跨任务，只保留同任务关键帧检索（退回上一轮 DG-KEYFRAME）。

### 3.5 LADE：延迟不是平均值，是 p99 预算

接口时间模型：

```math
T_{\mathrm{fb}} \approx \frac{T_a}{f_c} + \tau,
```

其中 `T_a` 是提交时固定的 `action_chunk_size`，`f_c` 是 evaluator 控制频率（未写死，必须实测），`τ` 是 RTT + 图像传输 + 伺服计算。`T_a` **不能运行时改**；能改的是：

- VLA plan 的刷新周期 `H_plan`（内部，30 步）；
- 快路径用「当前 plan + 检索 + 伺服」还是「只伺服」；
- 伺服增益/限幅（按 RTT 降档）。

调度器：

```python
def get_action(obs):
    t0 = now()
    anchor = tar.route(obs.language)          # <1ms
    plan = plan_buffer.get(obs, anchor)       # 非阻塞
    prior = xtsc.retrieve(obs, anchor)        # 5–20ms
    if plan is None or plan.stale:
        plan = plan_buffer.last_valid()       # 回退
    a_ff = plan.slice(T_a)
    a_cmd = servo.correct(a_ff, obs, prior)   # 5–20ms
    schedule_plan_refresh(obs, anchor)        # 后台线程，不阻塞
    return adapter.to_api(a_cmd, obs)
```

规则：

- 冷启动同步跑一次 VLA；之后 `get_action` **永不阻塞**等 VLA；
- plan 过期（`age > TTL`）→ 用旧 plan + 检索先验；连续过期 → 降增益/只做 PBVS；
- `get_action` p99 目标 ≤150ms（快路径），VLA 刷新 ≤1s；
- 延迟抖动作为可信度指标：固定 cadence、bounded compute、无阻塞、无 NaN/异常形状。

**与上一轮 CHUNK-SERVO 的差异**：上一轮是「30 步规划 + 5 步伺服」的固定双频；这一轮把「VLA 迟到时快路径用什么」补成**技能缓存先验**，并把 p99/抖动当一等指标。`T_a` 仍是提交前扫的超参数，不是运行时变量——这是对上一轮表述的修正。

**保留**：

- CHUNK-SERVO 的双频执行、5 步伺服、接触相位法向缩幅；

- 泛化：从「任务内关键帧」升级为「共享技能基 + 跨任务先验」。

**剪枝**：

- 运行时改 `action_chunk_size`（API 不允许；只在提交前扫 3/5/8/10）；

- 「用文本嵌入找相似任务做技能迁移」（r=-0.033，已证伪）；

## 6. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| `unnorm_key` 映射错 | 动作尺度错，整任务崩 | G0 先验证；key 错消融；置信度低用合并 norm/默认 key |
| 单模型解释 | 被判第二个模型 | 只有 WLA 是学习模型；TAR 是确定性路由；XTSC 是非参数记忆；伺服是控制器；提交材料写清 C1/C2/C3 |
| 技能缓存被当第二策略 | 合规风险 | 缓存只输出参考轨迹，不直接输出动作；动作由 VLA + 伺服产生 |
| 跨任务检索负迁移 | 成功率下降 | leave-one-task-out；IK/视觉/置信度门控；失败回退 VLA |
| 技能分段噪声 | 技能基不纯 | 用接触相位 + 人工校验子集；先 K=8–12，不追求细粒度 |
| 语言路由失败 | 选错任务/技能 | 160 条 + 中文词典 + VLM 文本最近邻 + 低置信度回退 |
| 中文评测不存在 | 投入浪费 | 中文只做离线增强/保险，不作为主收益 |
| RTT 高/抖动 | 伺服不稳 | `T_a` 提交前扫；增益调度；Smith/卡尔曼预测；p99 监控 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |

## 7. 一句话押注

**用 160 条释义把语言路由成 32 个任务锚点，用锚点选 `unnorm_key` 和共享技能基，用 33k 演示检索跨任务相对轨迹做伺服先验，用延迟感知的双频执行器保证 p99——在不新增学习模型的前提下，把「通才模型」从端到端黑箱变成「一个 VLA + 一个任务索引 + 一个技能记忆 + 一个控制器」。**

# 第 1 轮产物 · TASC 技术报告：任务锚点、技能因子与延迟预算

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。
>
> 本报告是第 1 轮想法区「TASC」的工程化产物；承接上一循环第 12 轮 **CHUNK-SERVO**，不替换它，而是把它从控制层扩展到「语言路由 + 技能共享 + 延迟调度」层。

## 0. 结论与边界

### 0.1 一句话结论

官方 WLA 的 30 步 action chunk 是吞吐优势，也是接触精度的结构性弱点；但比「最后 3 厘米」更靠前的一个缺口是：**32 个任务有 160 条语言释义，线上却没有一个把语言路由成任务锚点的层**。TASC 用 160 条释义学习 32 个结构化锚点，用锚点选 `unnorm_key`、任务嵌入和技能权重；用 33k 演示检索跨任务相对轨迹做伺服先验；用延迟感知的双频执行器保证 `get_action` 快路径 p99。最终仍然只有 **一个学习模型（WLA）**，路由/缓存/伺服都是确定性或非参数的。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、排行榜 JSON、WLA 代码直接核实 | 规则、API v2、33,276 eps、160 条释义、WLA `action_horizon=30`、`unnorm_key` 逻辑、榜单 29.7% |
| B | 我们在公开数据/网页上做的分析，可复现 | 榜单 `step~success` 回归、跨模型任务相关、语言-运动相关 r=-0.033、oracle 33.96% |
| C | 设计假设，需 G0–G7 验证 | TAR ≥95%、SKF +10pp、跨任务检索 +5pp、p99 ≤150ms |

### 0.3 本轮不做什么

- 不从零训 VLA/World Model；官方 WLA 已开源 6B 基座。
- 不做完整 sim-to-real 策略训练；数字孪生只做控制器风洞/可行性重排。
- 不做第二个学习模型/残差策略；TAR 是确定性路由，XTSC 是非参数记忆，伺服是控制器。
- 不做逐任务策略；用共享技能基 + 任务权重替代。
- 不做运行时改 `action_chunk_size`；API 固定，只在提交前扫。
- 不做 30Hz 广域网伺服；用固定 `T_a` + 双频。
- 不做 6D 物体位姿网络；用相对末端轨迹 + 腕部目标图。
- 不做力/触觉闭环；API 没有。
- 不把榜单任务排名当实测难度；只当预览。
- 不把「文本嵌入找相似任务」当技能迁移；已用 r=-0.033 证伪。

## 1. 事实核对

### 1.1 赛事与规则（A）

官方参赛手册（飞书 docx，2026-10-31 通过 `r.jina.ai` 抓取；稳定拿到 §1.1–§2.2，后续章节可能截断，最终以官方页面为准）核实：

| 项 | 规则 |
|---|---|
| 模型 | 所有任务须基于**同一模型**完成，不得混合多个模型一起测试；模型类型不限（World Model、VLA 均可） |
| 任务 | 32 项桌面任务 |
| 次数 | 每任务 10 次独立运行 |
| 泛化 | 5 类各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰 |
| 时限 | 单次真机执行上限 **180 s** |
| 排名 | 先比 32 任务总平均成功率；相同看总平均步骤分；再相同看更早提交 |
| 部署 | 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态必须隔离 |
| 测试通道 | 另有**不计分的单任务测试通道**，可用于单任务成功率/步骤分验证 |

**对方案的约束**：TASC 必须每端口独立、CPU 轻量、不抢 GPU；唯一学习模型是 WLA；TAR/XTSC/SERVO 不能是第二个策略。若官方对「模型」作最宽解释，走 §9 的 C1/C2/C3 合规模式。

### 1.2 提交 API v2（A）

提交模板当前为 **v2**（commit `edd0a1c9`，2026-08-21；旧版 `data_keys`/`obs_chunk_size` 文档仍在网上流传，必须以 main 分支为准）：

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640** |
| 本体 | 双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str` |
| 动作空间 | `control_space` 仅 `"joint"` 或 `"ee"`，二者互斥 |
| 共享动作 | `action.left_gripper [1]`、`action.right_gripper [1]`、`action.pivot [7]` |
| EE 动作 | `action.left_ee_pose_gripper_base [6]`、`action.right_ee_pose_gripper_base [6]`（绝对目标位姿，xyz+rpy，base 系） |
| chunk | `action_chunk_size` ≥1，**metadata 固定**；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action` |
| token | `metadata.token` 握手校验一次；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile、unnorm_key** |
| 监控 | 评测端逐调用记录 latency、variability、动作统计规律，作为结果可信度的一部分 |

**关键推论**：

1. `action_chunk_size` 是提交前参数，不能运行时改；运行时能改的是内部 plan 刷新节奏。上一轮「chunk size 是控制参数」应修正为「提交时的控制参数」。
2. 如果 `T_a=30`、`f_c=30Hz`，一次 `get_action` 后有 **1 秒开环执行**；如果 RTT=100ms，实际看到的世界比动作晚 100ms 以上。
3. `observation.language` 是单字符串、全程不变；它是**唯一的任务身份信号**，但没有配套的 `unnorm_key` 字段。
4. README §6 把 latency/variability 作为可信度的一部分；快路径必须平滑、有界、不阻塞。

## 2. 问题形式化

### 2.1 评分与统计

总分：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

320 trials 下，若 `p≈0.25`，单次标准误：

```math
\mathrm{SE}(S)\approx \sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

配对 A/B 的方差取决于任务内相关；同一初始条件的 A/B 成功高度相关时，配对差值方差可显著降低。报告必须给配对差值的 bootstrap 置信区间，而不是只报两个平均值。

人为干扰轴：

```math
\Delta S_{\mathrm{human}} = \frac{2}{10}\,\Delta p_h = 0.2\,\Delta p_h.
```

即 human 轴成功率 +10pp → 全局 +2pp。

### 2.2 接口时间模型（`T_a` 固定）

设：

- `f_c`：evaluator 控制频率（未写死，必须实测；数据是 30fps，假设 30Hz 起步）；
- `T_a`：提交的 `action_chunk_size`（固定）；
- `τ`：网络 RTT + 图像传输 + 伺服计算的等效延迟；
- `T_fb`：从「世界变化」到「策略看到变化」的反馈周期。

则：

```math
T_{\mathrm{fb}} \approx \frac{T_a}{f_c} + \tau.
```

| 场景 | `T_a` | `f_c` | `τ` | `T_fb` | 评价 |
|---|---:|---:|---:|---:|---|
| 官方 WLA 默认 | 30 | 30 | 50ms | **1050ms** | 接触段基本开环 |
| TASC 保守 | 5 | 30 | 50ms | **217ms** | 可做 1–2 次接触修正 |
| TASC 乐观 | 5 | 30 | 20ms | **187ms** | 需低 RTT |
| TASC 高延迟 | 5 | 30 | 150ms | **317ms** | 增益降档 |
| 低控制频率 | 5 | 10 | 50ms | **550ms** | 改 `T_a=3` 或只做 PBVS |
| 极低延迟 | 3 | 30 | 20ms | **120ms** | 动态任务可用 |

**结论**：`T_a` 必须按实测 `f_c` 和 `τ` 在提交前扫；不能把 30 步默认值直接搬到远程 API，也不能承诺运行时改。

### 2.3 任务锚点与技能因子

定义任务锚点：

```math
a_t = (\text{task\_id}_t,\ \text{verb}_t,\ \text{object}_t,\ \text{receptacle}_t,\ \text{constraints}_t).
```

技能基嵌入 `E = [e_1,\dots,e_K]\in\mathbb{R}^{K\times D}`，任务-技能权重 `W\in\mathbb{R}^{32\times K}`（非负、稀疏）。任务嵌入：

```math
e_{\text{task}}(t) = \sum_{k=1}^{K} W_{t,k}\, e_k .
```

DiT 的 AdaGN 条件：

```math
h_{\text{cond}} = \mathrm{MLP}\big(\mathrm{emb}(\tau_{\text{diff}}) + e_{\text{task}}(t)\big),
```

其中 `τ_diff` 是扩散时间步。`e_task` 只加在 action head，不改冻结的 VLM；参数量 `K×D + 32×K`，K=12、D=256 时约 3k，可忽略。

**可辨识性**：如果 `W` 退化为 one-hot，SKF 等价于 32 个独立任务嵌入（变体 B）；如果 `W` 均匀，SKF 等价于无任务条件（变体 A）。训练时用稀疏/非负约束和技能先验初始化，避免退化。

### 2.4 技能相对轨迹

对每个演示片段，定义相对末端轨迹：

```math
{}^{T_{\text{end}}}\!T_{ee}(t) = T_{\text{end}}^{-1}\,T_{ee}(t),
```

其中 `T_end` 是该片段结束时的 EE 位姿（或估计的受器位姿）。重采样到 L=32 步，得到 `rel ∈ R^{32×7}`（xyz + rotvec + gripper）。检索距离：

```math
d(q, r) = \mathrm{DTW}\big(\mathrm{rel}_q,\mathrm{rel}_r\big) + \lambda\, d_{\text{vis}}(I_q,I_r) + \mu\, d_{\text{anchor}}(a_q,a_r).
```

`d_anchor` 是锚点/技能权重距离；`d_vis` 是腕部图 ORB/颜色/边缘距离；DTW 允许速度差异。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
        ┌──────────────────────────────────────────────────┐
        │  Per-port TASC PolicyService (CPU)               │
        │  ├─ TAR: language → anchor → unnorm_key          │
        │  ├─ SKF: anchor → skill weights → task embedding │
        │  ├─ XTSC: anchor + obs → retrieved rel trajectory│
        │  ├─ LADE: plan buffer + deadline scheduler       │
        │  ├─ SERVO: 5-step visual/relative correction     │
        │  └─ ADAPTER: WLA 54D → API 21D; rpy↔rot6d        │
        └──────────────┬───────────────────────────────────┘
                       │ async, batched, per-port state
                       ▼
        ┌──────────────────────────────────────────────────┐
        │  Shared WLA server (GPU, one checkpoint)         │
        │  frozen Qwen3-VL + DiT action head (30-step)     │
        │  + skill-factorized task conditioning            │
        └──────────────────────────────────────────────────┘
```

- 每个端口一个 `PolicyService` 实例，独立 `reset()`、独立 plan buffer、独立 anchor/skill 状态。
- TAR/XTSC/SERVO 是 CPU 线程，不阻塞 websocket；VLA 请求异步、可批处理。
- 共享 WLA server 用 session ID 区分端口；模型权重只有一份，不违反单模型。
- GPU 6B bf16 约 12GB；一张 24GB/40GB GPU 可服务多个端口，具体并发取决于 batch 和序列长度。

### 3.2 TAR：语言 → 任务锚点 → `unnorm_key`

#### 3.2.1 锚点 schema

```python
anchor = {
    "task_id": 0,
    "verb": "hang",
    "object": "cup",
    "receptacle": "cup_rack",
    "constraints": ["marked_spot"],
    "skill_weights": {"reach":0.1, "grasp":0.2, "hang":0.7},
    "unnorm_key": "G1_Dex1_HangCup",
    "confidence": 0.98,
}
```

#### 3.2.2 锚点示例

| 任务 | object | receptacle | constraints | 主导技能 |
|---|---|---|---|---|
| HangCup | cup | cup_rack | marked_spot | hang |
| PlugInEthernet | ethernet_cable | network_port | insert | insert |
| DisconnectEthernet | ethernet_cable | network_port | extract | extract |
| StackBowls | bowls | stack | red→green→blue order | stack |
| ZipUp | storage_pouch | zipper | straighten | zip |
| PourOutMedicine | pill_bottle | container | unscrew cap | rotate+pour |

注意 PlugInEthernet 和 DisconnectEthernet 的 object/receptacle 相同，只有 verb/skill 不同。这正是「语言是索引」的价值：锚点能区分「插」和「拔」，而纯视觉/纯对象分类不能。

#### 3.2.3 路由流程

```python
def route(language):
    s = normalize(language)                  # lower, strip punctuation, synonyms
    if s in exact_index:                     # 160 variants
        return exact_index[s]
    scores = []
    for a in anchors:
        scores.append(keyword_score(s, a) + fuzzy_score(s, a))
    best = max(scores)
    if best.confidence >= 0.8:
        return best
    # same-checkpoint text encoder (C3), nearest neighbor over 160 anchor descriptions
    emb = wla_text_encoder(s)
    nn = anchor_emb_index.search(emb, k=5)
    if nn.confidence >= 0.6:
        return nn
    return task_agnostic_anchor(s)           # fallback: language-only
```

- `exact_index` 覆盖 160 条英文释义。
- 同义词表：hang/hook、plug/insert/connect、unplug/disconnect/detach、unlock/unfasten/release、fold/crease、stack/pile/layer、pack/store/stow、pick/extract/take…
- 中文词典：杯子/杯架、网线/网口、拉链、锁、药瓶、试管架、工具箱、耳机、手机、相框、书架、毛巾、针管…
- 中文回译：离线把 160 条释义翻译成中文，作为额外索引；上线不加载翻译模型。
- 低置信度回退：不路由 `unnorm_key`/技能，只把原始语言传给 WLA；用默认/合并 norm。

#### 3.2.4 为什么不是「语言分类器」

- 160 条释义的动词高度泛化，同一任务有 hang/hook、plug/insert/connect 等不同动词；动词分类器会错。
- 对象/受器/约束更稳定；同义词表 + 模糊匹配足够覆盖 160 条。
- 不训练第二个文本分类器；用确定性评分 + 同一 VLM 的文本编码器（C3）即可。

### 3.3 SKF：技能因子化动作头

#### 3.3.1 架构改动

```text
WLA DiT block:
  x = x + CrossAttn(x, VLM_features)
  x = x + AdaGN(x, cond)
  cond = MLP(timestep_emb + e_task)
  e_task = W[task_id] @ E          # (K,) @ (K,D) -> (D,)
```

- `W`：32×K，非负稀疏；`E`：K×D；`D` 与 DiT hidden 对齐（1024）或经线性投影。
- 初始化：`W` 用任务释义的动词/对象先验（plug→insert、hang→hang、stack→stack、zip→zip、pour→pour、fold→fold、unlock→rotate、sort→place…）；`E` 随机/正交初始化。
- 训练：冻结 VLM，只训 DiT + robot-state projector + `W`/`E`；24GB 可跑。
- 正则：`W` 的 L1 稀疏 + 非负；技能基正交/去相关；可选「技能权重平滑」——语义相近的任务（插网线/插充电器/整理试管）共享 insert 权重。

#### 3.3.2 消融矩阵

| 变体 | 条件 | 参数量 | 假设 |
|---|---|---:|---|
| A | 无任务嵌入（语言-only，baseline WLA） | 0 | 基线 |
| B | 32 个独立任务嵌入 | 32×D | 任务特化，小数据任务易过拟合 |
| C | K 个共享技能基 + 稀疏 W | K×D + 32×K | 共享正则，跨任务更好 |
| D | C + XTSC 检索先验 | + 非参数 | 技能先验 + 几何先验 |

**判定**：C 优于 B → 技能共享有价值；C 不优于 A → 语言条件已足够，SKF 降级为可选；D 优于 C → 检索先验有价值。

### 3.4 XTSC：跨任务技能缓存

#### 3.4.1 离线管线

```text
for each episode:
    T_ee(t), g(t) = state/action
    phases = change_point(T_ee velocity, angular velocity, g)
    for each phase:
        T_end = T_ee(phase.end)          # or estimated receptacle pose
        rel(t) = T_end^{-1} T_ee(t)
        rel_resampled = resample(rel, L=32)
        I_wrist_start/end = wrist images
        index.add(anchor, phase, rel_resampled, g, I_wrist, quality)
```

- 分段信号：EE 线速度/角速度、夹爪开度、`r_static`/`r_grasp`/`edit_score`（上一轮 GEO-RESIDUAL）；没有 subtask 标签，所以用无监督 change-point。
- 关键帧：接触前 1–3 帧、接触稳定后 1 帧、目标进入腕部视野且距离 <5cm 的帧。
- 质量分：重投影误差、腕部图清晰度、相位置信度、IK 可行率。
- 规模：33k episodes × 3–5 段 ≈ 100k–150k 段；每段 32×7 floats ≈ 1KB；总 ~150MB；腕部图可选 1–2GB。

#### 3.4.2 在线检索

```text
1. anchor filter: same task first; cross-task only if same skill/receptacle geometry
2. DTW on current relative-trajectory prefix vs candidates, top-k
3. visual rerank: wrist ORB/color/edge
4. feasibility rerank: IK/joint limits/collision (digital twin)
5. output rel* transformed to current base frame as servo reference
```

- 跨任务检索只在「同技能/同受器几何」时启用；否则只用同任务。
- 检索结果只做伺服参考，不直接输出动作；动作仍由 VLA + 伺服产生。
- 置信度低 → 回退 VLA 开环/上一轮 DG-KEYFRAME。

#### 3.4.3 leave-one-task-out 实验

- 对每个任务，把它自己的演示从缓存移除，只从其他 31 个任务检索。
- 指标：top-5 IK 可行率、DTW 距离、仿真/真机成功率。
- 如果跨任务不如「只用 VLA」，砍掉跨任务，只保留同任务关键帧检索。

### 3.5 LADE：延迟感知双频执行器

#### 3.5.1 调度器

```python
class LADEPolicy:
    def get_action(self, obs):
        t0 = now()
        anchor = self.tar.route(obs.language)          # <1ms
        plan = self.plan_buffer.get(obs, anchor)       # non-blocking
        prior = self.xtsc.retrieve(obs, anchor)        # 5–20ms
        if plan is None or plan.stale:
            plan = self.plan_buffer.last_valid()       # fallback
        a_ff = plan.slice(self.T_a)
        a_cmd = self.servo.correct(a_ff, obs, prior)   # 5–20ms
        self.schedule_plan_refresh(obs, anchor)        # background, non-blocking
        return self.adapter.to_api(a_cmd, obs, self.token)
```

规则：

- 冷启动同步跑一次 VLA；之后 `get_action` **永不阻塞**等 VLA。
- plan 过期（`age > TTL`）→ 用旧 plan + 检索先验；连续过期 → 降增益/只做 PBVS。
- `get_action` p99 目标 ≤150ms（快路径），VLA 刷新 ≤1s。
- 固定 cadence、bounded compute、无 NaN/异常形状；延迟抖动作为可信度指标。
- 每个端口独立 plan buffer/state；共享 VLA server 支持并发/批处理。

#### 3.5.2 延迟预算

| 组件 | 目标 p50 | 目标 p99 | 备注 |
|---|---:|---:|---|
| TAR 路由 | <1ms | <3ms | 词典/模糊匹配 |
| XTSC 检索 | 5ms | 20ms | FAISS/DTW top-k |
| SERVO | 5ms | 20ms | IBVS/PBVS |
| ADAPTER | 1ms | 5ms | 54D→21D, rpy↔rot6d |
| `get_action` 合计 | 15ms | **150ms** | 不含 VLA |
| VLA 刷新 | 200ms | 1000ms | 后台，30 步 plan |
| 网络 RTT | 20ms | 200ms | 实测/预测 |

#### 3.5.3 稳定性

简化离散积分器：

```math
e_{k+1}=e_k-K T_a\,e_{k-d},
```

其中 `d=τ/(T_a/f_c)` 是延迟块数。特征方程：

```math
z^{d+1}-z^{d}+K T_a=0.
```

- `d=0`：`|1-KT_a|<1` → `0<KT_a<2`。
- `d=1`：`z^2-z+KT_a=0`；稳定域 `0<KT_a<1`；增益裕度约减半。
- `d=2`：稳定域进一步缩小；必须降增益或加预测。

实践：

- 用 `τ` 测量值做 Smith 预测：`e_{k+d} ≈ e_k + J_v v τ`。
- 增益调度：`K_eff = K_0 / (1 + τ/τ_0)`；`τ_0` 取 50ms。
- 仿真扫 `τ ∈ {0,50,100,150}ms`；真机只允许在稳定域内。
- 如果 `T_fb > 300ms`，关闭 IBVS，只做 PBVS 粗对齐 + VLA。

### 3.6 动作适配（WLA 54D → 挑战赛 21D）

```text
WLA 54D:
  left_ee_rel[6], left_gripper[1], left_hand[6],
  right_ee_rel[6], right_gripper[1], right_hand[6],
  waist[3], torso[3], base_vxvy[2], base_wz[1],
  base_pose_rel[6], height[1], left_leg[6], right_leg[6]

挑战赛 ee 21D:
  left_ee_abs[6], right_ee_abs[6],
  left_gripper[1], right_gripper[1], pivot[7]
```

映射：

1. `left_ee_abs = compose(T_base_ee_left_current, exp(left_ee_rel))`；转 xyz+rpy。
2. `right_ee_abs` 同理。
3. gripper 直通（按挑战赛的 0–1 方向校验）。
4. `pivot = [vx, vy, wz, yaw, pitch, roll, height]`，从 WLA base/waist 组合；具体符号/顺序必须用 `example_env.py` 和单任务通道验证。
5. 腿部/灵巧手在挑战赛 `ee` 模式下不直接下发；若 `pivot` 需要下身体，按官方 WLA server 的 `action.pivot` 语义映射。

**rpy→rot6d**：

```math
R = R_z(\text{yaw})\,R_y(\text{pitch})\,R_x(\text{roll}),\qquad
\text{rot6d} = [R_{00},R_{10},R_{20},R_{01},R_{11},R_{21}].
```

WLA server 的 `left_ee_6d` 是 xyz+rot6d 9 维；挑战赛给的是 xyz+rpy 6 维，adapter 必须转换。

**关键细节**：WLA 的每个未来动作是「相对 plan-time 当前 EE」的位姿（compose 后才是 base 系绝对目标），不是累积增量；adapter 必须先把整个 30 步 compose 成 base 系绝对目标，再按 `T_a` 切片。否则切片后的第 6–30 步会以错误的锚点解释，产生系统性偏移。

**`unnorm_key`**：TAR 输出 `anchor.unnorm_key`；adapter 在请求里带上 `obs["unnorm_key"] = key`。如果 checkpoint 只有合并 norm，则用默认 key；如果 key 错，动作尺度会错，G0 必须做 key 错消融。

**帧/TCP 风险**：WLA 的 EE 帧与挑战赛的 `*_ee_pose_gripper_base` 帧可能差一个 TCP/夹爪长度偏移；必须用 `example_env.py` 的观测和真实数据做一次手眼/工具坐标校准（平移 ≤1cm、旋转 ≤2°）。这是 G0 的第一验证项。

**`pivot` 风险**：挑战赛 README 只写「Lower-body / pivot target」，没有逐维定义；WLA server 注释给的是 `[vx, vy, vw, yaw, pitch, roll, height]`。先用 `example_env.py`/单任务通道验证；不匹配时先返回全零 pivot（保持下身体不动），只验证双臂。

`PlanBuffer`：

```python
class PlanBuffer:
    def get(self, obs, anchor):
        p = self.current
        if p is None:
            return None
        if p.anchor.task_id != anchor.task_id:
            return None
        return p

    def request_refresh(self, obs, anchor, vla):
        if self.future is not None and not self.future.done():
            return
        if self.future is not None:
            self.current = self.future.result()
            self.future = None
        if self.current is None or self.current.age > self.ttl:
            snapshot = copy_obs(obs)
            self.future = self.executor.submit(vla.predict, snapshot, anchor)
```

规则：

- VLA 永远不阻塞 `get_action`（除冷启动）；plan 过期就用旧 plan + 伺服。
- 每个 chunk 只做一次伺服；伺服失败不影响返回合法动作。
- 任何异常 → 返回上一组合法 chunk 或安全 hold；绝不返回 NaN/错误形状。

### 4.3 E2：语言相似 ≠ 运动相似（B）

方法：

1. 32 个任务 × 5 条释义 → 词袋（去停用词、简单词干化）→ 两两 Jaccard。
2. 每个任务的 `action.left_arm/right_arm/left_gripper/right_gripper/pivot` + `observation.state.left_arm/right_arm` 的 mean+std → 逐维 z-score → 两两余弦。
3. Pearson 相关。

结果：

- **r = -0.033**。
- 语言最相似：DisconnectEthernet ↔ PlugInEthernet 0.556；ArrangePlates ↔ ColorArrangement 0.500；OrganizePencilCase ↔ PackBag 0.450。
- 运动最相似：OrganizePencilCase ↔ RemovePinnedNote 0.589；ColorArrangement ↔ OrganizeStationery 0.583；PackPhone ↔ PlacePhotoFrame 0.579；FruitSorting ↔ PaperCupStacking 0.574；HangCup ↔ FruitCollection 0.521。

**解释**：整条轨迹的全局运动统计混入了工作空间/手臂偏好/时长，不是「技能」。语言嵌入可以做任务锚点，不能做技能检索；技能检索要用**接触相位 + 相对轨迹 + 视觉目标**。

**边界**：这是 B 级分析，只用了 32 个任务的全局统计，不是接触相位级；结论是「不能直接用」，不是「永远不行」。

## 7. 创新点清单（持续迭代）

### 7.1 主投（P0）

#### I1. TAR：语言 → 任务锚点 → `unnorm_key` 路由

- **动机**：32 个任务有 160 条释义，但 WLA server 的 `unnorm_key` 不会从语言推断；挑战赛 API 没有 `unnorm_key`。语言字段存在，功能上是「哑」的。key 错 → 动作尺度错。
- **与现有方案差异**：baseline 把语言当 VLA 文本条件；TAR 把语言当路由键，同时解决归一化、任务嵌入、技能权重。
- **技术可行性**：高。160 条释义 + 同义词表 + 模糊匹配即可；中文用离线回译/词典；低置信度回退。无需第二个学习模型。
- **所需资源**：CPU；160 条释义；32 个任务名；中文词典；1 人周。
- **落地步骤**：① 抽取 32 个锚点；② 建 160 条索引 + 同义词/中文词典；③ 单任务通道验证 key 路由；④ key 错消融；⑤ 低置信度回退。
- **风险**：释义覆盖不足；中文评测不存在；key 映射歧义。缓解：模糊匹配 + VLM 文本最近邻 + 合并 norm 回退。
- **证据**：A（WLA 代码/API）+ C（收益待测）。

#### I2. SKF：技能因子化动作头

- **动机**：32 个任务共享插入/挂/叠/拉链/拧/倒/折等接触原语，但端到端模型没有显式共享基；语言相似 ≠ 运动相似（r=-0.033），所以共享必须来自动作/接触结构，不是文本。
- **与现有方案差异**：baseline 是纯语言条件 DiT；SKF 用 K 个共享技能基 + 32×K 稀疏任务权重，把任务特化和跨任务共享分开。
- **技术可行性**：中高。只改 DiT 条件，冻结 VLM；24GB 可训；参数量 ~3k。
- **所需资源**：1×24GB GPU；33k 演示；WLA 微调代码；2–3 GPU 周；1 人。
- **落地步骤**：① 技能组先验初始化 W；② 训练 A/B/C 变体；③ 验证损失 + 单任务 A/B；④ 若 C 不优于 A/B，砍掉。
- **风险**：任务嵌入冗余（语言已足够）；小数据任务过拟合；技能基不可解释。缓解：稀疏/非负、技能组初始化、消融。
- **证据**：A（WLA 代码）+ B（语言-运动负结果）+ C（收益待测）。

#### I3. XTSC：跨任务技能缓存

- **动机**：33k 成功演示不只是 imitation 数据，也是「相对轨迹 + 腕部目标图」库；最后 3 厘米需要几何先验，VLA 的语义先验不够。
- **与现有方案差异**：上一轮 DG-KEYFRAME 检索同任务目标关键帧；XTSC 检索跨任务相对轨迹，允许从其他任务借运动先验。
- **技术可行性**：中。无 subtask 标签，需要无监督分段；检索/DTW/IK 重排可 CPU 化；缓存只做伺服参考，不直接输出动作。
- **所需资源**：33k 演示；CPU 16–32 核；150MB–2GB 存储；2 人周。
- **落地步骤**：① 分段 + 相对轨迹库；② leave-one-task-out 检索评测；③ IK/视觉重排；④ 接入伺服；⑤ 若负迁移，退回同任务。
- **风险**：分段噪声；跨任务负迁移；被当第二策略。缓解：接触相位 + 置信度门控 + 只做参考 + 合规说明。
- **证据**：A（数据）+ B（语言-运动负结果）+ C（收益待测）。

#### I4. LADE：延迟感知双频执行器

- **动机**：6B + 远程 API；`T_a` 固定；评测端记录 latency/variability；VLA 迟到时快路径不能空转。
- **与现有方案差异**：上一轮固定 5 步伺服；LADE 用 plan buffer + deadline 调度 + p99 指标 + 技能缓存快路径；`T_a` 提交前扫，不在运行时改。
- **技术可行性**：高。纯工程；线程池 + plan buffer + 超时回退；无需新模型。
- **所需资源**：CPU；1 GPU 共享 server；1 人周。
- **落地步骤**：① 测 `f_c`/RTT/推理延迟；② 扫 `T_a` 3/5/8/10；③ plan buffer/超时回退；④ p99/抖动监控；⑤ 全量干跑。
- **风险**：RTT 高；plan 过期；并发端口互相阻塞。缓解：异步/批处理/每端口隔离/降增益。
- **证据**：A（README §6/API）+ C（收益待测）。

### 7.2 备选（P1）

#### I5. PARA-AUG：160 条释义 + 中文回译增强

- **动机**：数据已有 5 条英文释义；中文是潜在评测语言（未证实）。
- **差异**：baseline 已随机抽 1 条；我们加「锚点监督」——释义 → 锚点，而不是只做文本增强。
- **可行性**：高；离线翻译/词典；不训练上线翻译模型。
- **资源**：CPU；1 人周。
- **步骤**：① 中文回译 160 条；② 建双语词典；③ 路由评测；④ 若中文不评测，保留为保险。
- **风险**：中文评测不存在；翻译噪声。缓解：只做离线增强/保险。
- **证据**：A（数据）+ C。

#### I6. CONTACT-SEG：无监督接触相位分割

- **动机**：没有 subtask 标签；技能缓存/相位伺服需要分段。
- **差异**：上一轮用人工/启发式相位；本轮用 EE 速度/夹爪/接触残差 change-point。
- **可行性**：中高；CPU 可跑；用少量人工标签校验。
- **资源**：33k 演示；CPU；1–2 人周。
- **步骤**：① 信号设计；② change-point；③ 人工校验 100 段；④ 接入 XTSC。
- **风险**：分段噪声；透明/变形任务不准。缓解：只对刚体接触任务启用。
- **证据**：A（数据）+ C。

#### I7. TWIN-SCORE：数字孪生可行性重排

- **动机**：检索出的轨迹可能不可达/碰撞；需要几何过滤。
- **差异**：不用学习世界模型；用 G1 URDF + IK/碰撞做确定性重排。
- **可行性**：高；MuJoCo/IsaacLab 已有；CPU/GPU 均可。
- **资源**：G1 URDF；仿真环境；1 人周。
- **步骤**：① 搭 3 个任务族；② IK/碰撞检查；③ 接入 XTSC 重排；④ 仿真压测。
- **风险**：sim-to-real gap；只做排序不做预测。缓解：只做可行性门控。
- **证据**：A（官方仿真）+ C。

### 7.3 明确剪枝（P2，不做）

| 方向 | 为什么不做 |

## 9. 风险与合规

### 9.1 单模型合规的三种模式

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | TAR/XTSC 只离线生成锚点/技能标签；线上只有 VLA | 最低 | 保守首选 |
| C2 确定性控制器 | TAR 是词典/模糊匹配；XTSC 是非参数记忆；伺服是几何/控制律；VLA 是唯一学习模型 | 低；需向官方说明 | 主推 |
| C3 同 checkpoint 特征 | 文本/视觉描述子用 WLA 同一 checkpoint 的 encoder，不加载第二个模型 | 低–中；需说明 | 需要强描述子时用 |

禁止：加载第二个学习策略/残差网络/独立视觉编码器做在线决策。

### 9.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| `unnorm_key` 映射错 | 动作尺度错，整任务崩 | G0 先验证；key 错消融；置信度低用合并 norm/默认 key |
| 单模型解释 | 被判第二个模型 | 只有 WLA 是学习模型；TAR 确定性；XTSC 非参数；伺服控制器；提交材料写清 C1/C2/C3 |
| 技能缓存被当第二策略 | 合规风险 | 缓存只输出参考轨迹，不直接输出动作；动作由 VLA + 伺服产生 |
| 跨任务检索负迁移 | 成功率下降 | leave-one-task-out；IK/视觉/置信度门控；失败回退 VLA |
| 技能分段噪声 | 技能基不纯 | 用接触相位 + 人工校验子集；先 K=8–12 |
| 语言路由失败 | 选错任务/技能 | 160 条 + 中文词典 + VLM 文本最近邻 + 低置信度回退 |
| 中文评测不存在 | 投入浪费 | 中文只做离线增强/保险，不作为主收益 |
| RTT 高/抖动 | 伺服不稳 | `T_a` 提交前扫；增益调度；Smith/卡尔曼预测；p99 监控 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |
| `pivot` 语义不一致 | 动作被拒/机器人不动 | 先用 `example_env.py`/单任务通道验证；保留零 pivot 回退 |
| 提交次数限制 | 无法多次 A/B | 邮件确认；单任务通道先验证；一次提交则保守 |
