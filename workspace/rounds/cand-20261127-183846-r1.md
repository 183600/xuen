## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（强化学习 → 这场比赛的 RL 不是探索，而是把「全成功示教」变成「有优劣的排序」）**

直觉：标准 RL 需要环境、奖励和探索；这场比赛三样都不成立——32 任务没有对齐的官方仿真（F14 的 sim 与赛题无直接对齐），真机通道稀缺，评测期禁止在线学习。但数据并非「无奖励」：官方每任务 100 分得分点（F17）就是天然的密集里程碑奖励；而 32k 条示教全部成功（P8），意味着数据里没有「失败」的负样本，却有「同样成功、谁更快/更完整」的效率差异。于是 RL 在这场比赛里的正确形态是**离线价值学习**：从成功示教中学习 return-to-go / advantage，再用它做数据重加权与候选重排。核心反直觉点：**在全是成功样本的数据集上，RL 不是学「怎么成功」，而是学「哪种成功更值钱」；它首先是一个数据重估器，而不是一个探索算法。**

严谨地说：对任务 k，官方得分点 \(g_{k,1},\dots,g_{k,m_k}\) 与权重 \(w_{k,j}\)（\(\sum_j w_{k,j}=100\)）。用里程碑检测器 \(G_{k,j}(s_t)\) 表示截至 t 是否达成，定义累计分 \(S_t=\sum_j w_{k,j}\mathbf{1}[\exists t'\le t:G_{k,j}(s_{t'})=1]\)，密集回报 \(r_t=S_t-S_{t-1}\ge0\)，return-to-go \(V^\pi(s_t)=\mathbb{E}_\pi[\sum_{t'\ge t}\gamma^{t'-t}r_{t'}\mid s_t]\)。策略优化目标不是最大化环境奖励（环境不提供），而是最大化这个由官方计分反推的回报。全成功数据下 \(V\) 的方差主要来自「到达同一得分点的时间差」与「路径/平滑度」，这正是步骤分在时间约束下的可优化空间。

但必须承认：只有成功数据时，优势加权 BC 很容易退化为普通 BC——因为所有样本最终都成功，回报差异小。要让 RL 真正有用，必须人为制造「相对失败」：I5 的扰动重放/跨段缝合给出低回报延续段，I1 的反事实扰动给出同一状态下的差动作。**因此 I10 不是独立模块，它依赖 I5/I1 提供负样本与反事实；顺序是「先造数据，再学价值」。**

**灵感 2（决策规划 → 规划不是 rollout，而是「在哪一层做决定、花多少计算」）**

直觉：32 任务里有一类任务的分数由「先拿哪个、放哪里」决定——ArrangePlates、PackBag、ToolboxStorage、ConveyorSorting、ColorArrangement 等多物体/排序任务；另一类任务（PlugCharger、ZipUp、PourOutMedicine）的分数由接触段的短周期修正决定。一个 flat 的 chunk 策略无法同时把这两层做好：长 chunk 承诺在接触段危险，短 chunk 在高层的物体排序上又浪费重规划。决策规划的正确切入点是**分层**：任务级用符号/拓扑规划决定顺序（零训练、CPU 级），chunk 级用学习到的价值头在少数候选间选择（便宜、可批量），per-step 只保留安全 guard（I4/I6）。核心反直觉点：**决策规划的第一性问题不是「下一个动作是什么」，而是「这个决定应该在哪一层做、值多少计算」；把规划放在 chunk 边界，既避开 66ms 单步预算，又保留任务级重规划能力。**

严谨地说，这是一个半马尔可夫决策过程（semi-MDP）：高层选项 \(o=(I_o,\pi_o,\beta_o)\)，其中 \(\pi_o\) 是 VLA 的 chunk 策略，\(\beta_o\) 是终止/切换条件；高层价值 \(Q(s,o)\) 在 chunk 边界评估。任务级排序则是一个带先序约束的调度问题：子任务 \(i\) 有得分权重 \(w_i\)、预计耗时 \(\tau_i\)、成功率 \(p_i\)、先序 \(\prec\)，在剩余时间 \(T\) 内最大化 \(\sum_i p_i w_i \mathbf{1}[\text{completed before }T]\)。小规模可用拓扑贪心 \(p_iw_i/\tau_i\) 或 DP 精确解。这个层次不需要训练，却能吃掉多物体任务里「顺序错误导致超时/无效移动」的分数。

**灵感 3（两者碰撞 → 价值引导的分层策略，而不是新模型）**

直觉：RL 提供价值信号，规划消费价值信号。I10 训练一个很小的 return-to-go/优势头；I11 用同一个头做两件事：任务级排序时估计各子任务的 \(p_i\) 与剩余价值，chunk 级在 K 个候选间做 \(Q(s,a)\) 重排；当价值高且稳定时延长 chunk，当价值低或集成方差高时缩短 chunk、进入恢复模式（调用 I3/I5 先验）。整个过程不新增基座、不交互环境、不更新权重。三道闸的对应关系：计分轴对齐——奖励直接来自官方得分点；单模型边界——价值头/规划器是 PolicyService 内部组件（需书面确认）；部署预算——价值头 <1% 参数，K≤3 候选在 chunk 边界批量生成，且有一键降级到 K=1。

三者统一：**I2/I5 把数据分布做对，I10 把「都对」的数据变成「有优劣」的价值信号，I11 把价值信号变成「任务级顺序 + chunk 级选择」的决策。顺序不能反：没有数据引擎的价值学习只会放大噪声；没有价值信号的分层规划只是硬编码状态机。**

## 2. 对 v1.1 痛点的增量修订

- P1（弱任务支配平均分）：I10 的 per-task 归一化优势可把弱任务的高价值片段提权；但新增风险是采样坍缩到少数片段，需最低采样率保护。
- P2（泛化缺口）：I11 的任务级重规划能在新布局/新物体数量下重新排序，是 I1/I9 之外第三条泛化路径；但它依赖 VLM 感知，误检会放大。
- P5（时间压力）：return-to-go 显式优化「到达得分点的时间」，与步骤分的时间约束（F3）同向；这是 I10 相对 BC 最直接的收益来源。
- P7（先手窗口）：官方仓库无 RL/价值/规划模块（F21），说明这块是空白区；先手不只是模型权重，还包括「得分点→回报→OPE」这条评估管线。
- 新增 P9（离线 RL 评估缺口）：没有离线成功率，OPE 在 success-only 数据上高方差；I10/I11 的增益很难在真机前被可靠证明。
- 新增 P10（规划延迟与承诺）：K 候选 × chunk 生成可能超 p99；长 chunk 降低反应性；任务级排序可能因 VLM 误检而错序。
- 新增 P11（奖励标注噪声）：得分点尚未完全逆向，里程碑检测器误差会污染回报，导致价值头学视觉捷径或奖励黑客。

## 3. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

- **Q9（密集回报提取）**：官方得分点能否被可靠地转成密集回报？每个任务最少需要多少里程碑标注？如何处理只有最终成功、没有中间步骤的任务？成功率与步骤分的字典序约束如何标定？
- **Q10（success-only 下的离线价值学习）**：return-to-go/优势加权相对匹配预算的 BC 是否真能提升步骤分？何时退化为 BC？需要多少 I5 合成失败/I1 反事实样本才能让恢复行为可学？哪条 OPE 代理与真机增益最相关？
- **Q11（分层规划的粒度）**：哪些任务对顺序敏感？任务级排序相对 flat 策略的增益有多大？chunk 级 K 重排在匹配延迟下是否优于 K=1？K、chunk 长度、成功率/步骤分的 Pareto 前沿是什么？规划器何时应该弃权（不确定性阈值）？

## 4. 设计原则（新增 PR6/PR7，PR1–PR5 保留）

- **PR6 价值信号律**：任何 RL/规划增益必须能归因于「BC 目标里没有的价值信号」；若打乱回报或随机化 critic 后增益仍存在，说明只是正则化/容量效应，不能算 RL 的贡献。与 PR5 互补：PR5 管数据来源，PR6 管价值归因。
- **PR7 决策粒度律**：每个决定应放在能表达该约束的最粗层级；只有接触/不确定性要求时才下探更细层级。推论：单物体任务不做任务级排序；稳定高分时不生成 K 个候选；per-step 不做学习型规划。
- PR1–PR5 保留（第 1 轮 §4、第 2 轮 §4）。

## 6. 本轮最大风险

**一句话**：I10 的价值信号建立在「官方得分点可被可靠逆向 + 全成功示教中存在可学的效率差异」两个假设上；若得分点标注有噪声或任务本身没有效率方差，优势重加权会退化为普通 BC，而 I11 的 chunk 重排会把 critic 的偏差放大成自信的错误决策——这是本轮必须先过 L0 奖励消融与 OPE 校准、再上真机的点。

> 检索日期：2026-11-26（第 1 轮）、2026-11-27（第 2 轮）、2026-11-27（本轮）；来源见 §7。承接 v1.1：I7 裁撤推理路径，I2/I5/I8 深化，新增 I10/I11。清单只增改不重置。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I1 v3 考纲校准五轴增广引擎 ★★★★★
- **动机/差异/可行性/资源**：同 v1.1（考纲卡 + 剂量-响应 + 轴间析因；1×24GB GPU）。
- **本轮增量**：增广器多了一个用途——为 I10 生成**反事实状态-动作对**：同一状态下的原动作 vs 受扰动作，其后续得分点达成差异提供偏好/优势标签。I1 因此不只是「扩数据」，还是「造负样本/造反事实」的基础设施。
- **落地补充**：3 个试点任务（PlugCharger/ZipUp/PourOutMedicine）的增广输出同时打两份标签（下一得分点是否达成、达成时间），供 I10 的 return-to-go 回归使用。
- **风险**：反事实动作的物理可行性仍需 L0 过滤（不可行动作占比 >5% 降级为仅平移不变增广）。

### I2 v3 数据引擎 3.0：孪生迁移 + 优势加权共训 ★★★★★
- **动机**：同 v1.1（单模型平均分被最弱任务支配；示教语料与质量双重浪费）。
- **本轮深化**：保留三件事（孪生语料、loader 加权 patch、质量加权），把「质量分」升级为「得分点优势分」——用 I10 的 return-to-go/advantage 替代手工质量分；采样权重按**任务内分位数**归一化，避免长任务/短任务互相压制。
- **与现有方案差异**：从「静态质量加权」升级为「价值加权」；但只在 L0 证明优势估计可信后启用，默认仍是质量加权（保守回退）。
- **技术可行性**：高（LoRA/frozen-VLM 单卡起步，F11；全参 action expert 4–8 卡）。
- **所需资源**：孪生子集 ≈1–2TB + 32 任务 ≈2TB；训练 1×24GB 起步。
- **落地步骤**：①孪生表；②loader patch + 频率单测；③首轮共训；④I10 价值头上线后切换为优势加权；⑤族级 L0 消融验证正迁移后放量。
- **风险**：优势估计噪声 → 采样坍缩到少数高优势片段；缓解：权重裁剪 + 每任务最低采样率 + 随机权重基线对照；负迁移风险同 v1.1。

### I3 接触任务族关键点视觉伺服回退 ★★★★（维持，角色变化）
- 六要素同 v1.1：通用 chunk 策略负责接近段、几何伺服负责接触段，同一策略服务内混合推理；关键点用开放词汇检测零训练起步；触发滞回 + 低置信回退；I3' 降级预案保留。
- **本轮定位变化**：I3 从「主恢复路径」降为 I11 的一个**接触级选项**——当 critic 不确定性高且任务处于接触段时，规划器可切换到几何伺服短 chunk；不是所有任务默认启用。
- **风险/合规**：单模型边界待组委会书面确认；确认前不上计分通道。

### I4 人手干预感知门控 + 自适应 chunk ★★★★（升级为「预算自适应」）
- 六要素同 v1.1：手部检测 + `obs_delta_indices` 历史栈做干预判别（<50ms）；状态机 INTERFERED→停持→重估→续做；停持动作界内平滑。
- **本轮增量**：chunk 长度不再只用固定档位，而由 I11 的 critic 不确定性 + 干预状态共同决定：稳定高分 → 长 chunk（16）；不确定/接触/干预 → 短 chunk（4–6）+ 更高重规划频率。形成「价值引导的自适应 chunk」。
- **风险**：critic 不确定性校准不好 → 频繁切换；缓解：滞回 + 切换代价惩罚。

### I5 v3 非标称示教合成 + 得分点对齐恢复 ★★★★★（升级）
- **动机**：步骤分 = 官方得分点制（F17，每任务满分 100）；超时仍按进度计步骤分（F3）；数据集全成功、无失败示教（P8）。
- **本轮深化**：保留 v1.1 的四步（扰动重放、跨段缝合、WMA 生成、得分点过滤），新增第五步——**负样本化**：合成失败段不仅用于 BC，还作为 I10 的负样本/反事实对；同一状态，原成功延续段 vs 扰动后失败/低分延续段，构成偏好对。这解决「全成功数据无负样本」导致离线 RL 退化的问题。
- **与现有方案差异**：v1.1 只把合成示教当正样本；v3 把它们同时当**相对负样本**，服务于价值学习。
- **技术可行性**：中-高。扰动重放与缝合是纯数据工程；里程碑检测器 = 轻量视觉分类器（官方数据自监督标注种子 + 人工抽检）。
- **所需资源**：1×24GB GPU；数据工程 2 人周；检测器训练 1 GPU 日/任务族。
- **落地步骤**：①得分点逆向；②3 个弱任务试点合成管线；③为每段记录「剩余得分点序列」作为 return-to-go 标签；④进度头改得分点监督；⑤LoRA 增量训练；⑥单任务通道 A/B。
- **风险**：合成失败分布与真实偏离失配（缓解：扰动幅度从考纲卡采样 + 真机抽测）；里程碑检测器误差污染标签（缓解：置信门控 + 人工抽检 5%）。

### I6 确定性低延迟部署服务 ★★★★（维持）
- 六要素同 v1.1：共享 backend + 每端口独立队列与 episode 状态隔离、fp8/INT8 量化、torch.compile/CUDA Graph、obs 预取、`image_resize` 压带宽、断线重连 + 健康探针（PR4 门禁）。
- **本轮新增**：为 I11 的 K 候选生成预留批量推理接口（一次 forward 出 K 个 chunk），并加「规划器降级开关」——p99 超预算时自动退回 K=1。
- **风险**：批量候选显存/延迟；缓解：K≤3、候选并行、critic 极小、必要时蒸馏。

### I7 世界模型测试时前瞻 —— 裁撤（推理路径）
- **本轮决定**：裁撤 I7 的 test-time rollout。理由：F21 表明官方无 RL/规划框架，I7 的 O(N) 次世界模型 rollout 与 66ms/1s 级预算冲突；I11 的 model-free chunk 价值选择能以更低成本获得大部分收益。
- **资产去向**：WMA-0 的仿真模式（F15）转入 I5 v3 的数据合成，以及 I10 的反事实数据生成；不废弃，但不再占用评测时预算。

### I8 v3 评测运营闭环 + 分级消融 + OPE 注册表 ★★★★
- **动机**：真机通道稀缺 + 待验证组合爆炸（P7）；离线 RL/规划缺少可靠的成功率代理（P9）。
- **本轮深化**：保留 L0/L1/L2 分级与离线-在线相关性注册表，新增 **OPE（离线策略评估）子协议**——FQE、return-to-go 校准、动作似然、里程碑进度四条代理；每条代理单独登记与真机增益的相关性；RL/规划类改动必须先过 OPE 门槛（如 Spearman>0.6）才允许进入 L2。
- **技术可行性**：高（L0 纯离线计算）。
- **所需资源**：代理指标实现 1 人周；注册表 = 表格 + 评测脚本。
- **落地步骤**：①四条代理实现；②注册表 schema；③首个真实用例 = I10 的 AWBC vs BC；④每月复盘相关性。
- **风险**：OPE 在 success-only 数据上方差大；缓解：只在小候选集上用、报告置信区间、不以 OPE 单独做最终决策。

### I9 reset 期检索类比迁移 ★★★★（维持）
- 六要素同 v1.1：`reset()` 每 episode 恰好一次（F18），用 VLM/DINOv2 嵌入检索「物体-技能库」，结果作软先验/门控偏置；零权重更新。
- **本轮接口**：检索结果可作为 I11 任务级规划器的「物体-技能先验」（例如新外观杯子 → 抓取高度/开度），以及 chunk 候选生成的初始条件；不改变 I9 的零权重更新定位。
- **风险/合规**：误检索伤标称任务（距离阈值门控）；reset 期检索合规性书面确认。

### I10 得分点回报的离线价值学习 + 优势重加权（新） ★★★★★
- **动机**：官方数据全是成功示教，BC 把所有示教当等优；但官方步骤分（F17）提供了「同样成功、谁更快/更完整」的密集信号。RL 在这场比赛里不应做在线探索（无对齐仿真、真机稀缺、评测期禁在线学习），而应做**离线价值学习**：学 return-to-go / advantage，再用于数据重加权与 chunk 重排。
- **与现有方案差异**：普通 BC/SFT 只拟合动作；DPO/RLHF 需要偏好数据；本点用官方得分点自动构造密集回报，用成功示教中的效率差异学价值，不新增基座、不交互环境。
- **技术可行性**：中-高。价值头 = 冻结 VLM latent + proprio + action-chunk embedding 上的小型回归头（<1% 参数量）；奖励来自得分点里程碑检测器（I5）；负样本来自 I5 合成失败与 I1 反事实扰动。训练是监督回归（return-to-go），不是不稳定的 TD/策略梯度。
- **所需资源**：1×24GB GPU（与主训练共用）；价值头训练 1–2 GPU 日；得分点标注 3 个试点任务 2 人周。
- **落地步骤**：①3 个试点任务逆向得分点（PlugCharger/ZipUp/PourOutMedicine）；②训练里程碑检测器（视觉分类 + 置信门控）；③构造 return-to-go 标签；④训练 chunk 价值头；⑤AWBC（优势加权 flow-matching）与匹配预算 BC 对比；⑥加入 I5 负样本做偏好/优势消融；⑦L0 OPE + L1 小真机。
- **风险**：全成功数据 → 优势方差小、退化为 BC；得分点噪声 → 价值头学视觉捷径；成功与步骤分冲突 → 需要字典序约束。缓解：每任务归一化 + 奖励消融（打乱回报看增益是否消失）+ 反事实外观/背景测试 + 成功优先的候选过滤。

### I11 分层决策规划：任务级排序 + chunk 级价值选择（新） ★★★★
- **动机**：多物体任务（ArrangePlates/PackBag/ToolboxStorage/ConveyorSorting/ColorArrangement）的分数由「先拿哪个、放哪里」决定；接触任务又要求短周期反应。单一 flat chunk 策略无法同时优化这两层。
- **与现有方案差异**：I7 用世界模型 rollout 做前瞻（贵、慢）；本点用**model-free 价值头**在 chunk 边界做候选重排，任务级用符号/拓扑规划，不产生额外环境交互。
- **技术可行性**：高-中。任务级：VLM 解析物体/目标 + 得分点权重 + 拓扑排序/贪心（零训练）；chunk 级：VLA 批量采样 K=2–3 个候选，价值头打分，argmax + 不确定性惩罚。critic 与 I10 共用。
- **所需资源**：1 人周工程 + 现有 GPU；任务级规划器 CPU 即可；延迟预算见 §3。
- **落地步骤**：①标注 5–8 个 order-sensitive 任务；②实现任务级 precedence graph + score-per-time 贪心/DP；③实现 K 候选 chunk 生成 + 价值重排；④不确定性触发：高分歧 → 短 chunk/恢复模式/调用 I3；⑤L0 replay + 延迟基准；⑥L2 真机 A/B（K=1 vs K=3；有/无任务级排序）。
- **风险**：critic 偏差被重排放大；VLM 任务级感知错误；K 候选延迟超预算；长 chunk 承诺导致不可恢复。缓解：不确定性门控 + K 上限 + 规划器可一键降级 + 接触段强制短 chunk。

## 1. 形式化与关键推导

### 1.1 把官方步骤分变成密集回报

对任务 k，设官方得分点 \(g_{k,1},\dots,g_{k,m_k}\)，权重 \(w_{k,j}\)，\(\sum_j w_{k,j}=100\)。用里程碑检测器 \(G_{k,j}(s_t)\in\{0,1\}\) 表示截至 t 是否达成。定义累计分与密集回报：

\[
S_t=\sum_{j=1}^{m_k} w_{k,j}\cdot \mathbf{1}\left[\exists t'\le t: G_{k,j}(s_{t'})=1\right],
\qquad
r_t=S_t-S_{t-1}\ge 0.
\]

若成功率为独立指标，采用**字典序目标**：先约束成功率（候选 chunk 必须通过成功判别/高置信里程碑），再最大化 \(S_T\)。价值定义为 return-to-go：

\[
V^\pi(s_t)=\mathbb{E}_\pi\left[\sum_{t'=t}^{T}\gamma^{t'-t} r_{t'}\ \middle|\ s_t\right].
\]

在 chunk 粒度上，动作是 \(a_{t:t+H}\)，优势 \(A(s_t,a_{t:t+H})=Q(s_t,a_{t:t+H})-V(s_t)\)，其中 \(Q\) 的回归目标是该 chunk 执行后的实际 return-to-go \(G_t\)（离线数据可直接算）。注意：这里不学 Q 的 TD 目标，而学 **chunk 条件 return-to-go 回归**，避免 offline RL 的外推误差。

### 1.2 优势加权 flow-matching（AWBC）

基线 flow-matching 损失（以速度场参数化为例）：

\[
\mathcal{L}_{FM}(\theta)=\mathbb{E}_{(s,a)\sim D,\,t\sim U[0,1],\,\epsilon}\left\|v_\theta(a_t,t,s)-(a-\epsilon)\right\|^2 .
\]

AWBC：

\[
\mathcal{L}_{AWBC}(\theta)=\mathbb{E}_{(s,a)\sim D}\left[\mathrm{clip}\left(e^{A(s,a)/\beta},w_{\min},w_{\max}\right)\cdot \mathcal{L}_{FM}(\theta;s,a)\right].
\]

优点：不需要环境交互、不需要策略梯度；缺点：全成功数据下若 \(A\) 方差小则退化为 BC。因此必须有 I5 的合成失败/I1 的反事实来扩大 \(A\) 的支撑。可选的偏好对版本（DPO）作为消融，不作为主路径——因为 flow/diffusion 策略的 DPO 实现更复杂，且 success-only 偏好对更稀缺。

### 1.3 chunk 价值头与候选重排

价值头 \(Q_\phi(s,z_a)\approx G_t\)，输入 = 冻结 VLM 的 scene latent + proprio + 动作 chunk 编码 \(z_a\)；另有一个 state-value 头 \(V_\psi(s)\) 用于优势基线。训练目标：

\[
\mathcal{L}_V(\phi,\psi)=\mathbb{E}_{(s,a,G)\sim D}\left[\mathrm{Huber}\left(Q_\phi(s,z_a)-G\right)+\mathrm{Huber}\left(V_\psi(s)-G\right)\right].
\]

推理时，VLA 批量采样 K 个候选 \(\{a^{(k)}\}_{k=1}^K\)，选

\[
a^\*=\arg\max_k \left[Q_\phi(s,z_{a^{(k)}})-\lambda\cdot \mathrm{Unc}(s,a^{(k)})\right],
\]

其中 \(\mathrm{Unc}\) 用 2–3 个价值头的集成方差近似。若 \(\max_k Q\) 低或 \(\mathrm{Unc}\) 高 → 进入恢复模式（短 chunk + I3/I5 先验）；若高且稳定 → 延长 chunk（I4）。这就是「价值引导的自适应 chunk + 选项选择」。

**关键安全性质**：候选动作来自策略自身的采样，而不是对动作空间的任意优化；因此离线价值头只在策略支撑集附近被查询，显著缓解 offline RL 的外推误差（OOD action）问题。

### 1.4 任务级排序

对多物体任务，构造子任务集合 \(\{(w_i,\tau_i,p_i,\prec)\}\)：\(w_i\) 是该物体/槽位对应得分点权重，\(\tau_i\) 是预计耗时（同类任务历史均值），\(p_i\) 是 VLM/价值头给的预计成功率，\(\prec\) 是先后约束。目标是

\[
\max_{\text{topological order }\sigma}\ \sum_i p_{\sigma(i)}w_{\sigma(i)}\cdot \mathbf{1}\left[\sum_{j\le i}\tau_{\sigma(j)}\le T_{\text{remain}}\right].
\]

小规模（m≤8）可用 bitmask DP 精确解：

\[
F(S,t)=\max_{i\in \mathrm{ready}(S)}\left[p_iw_i\mathbf{1}[\tau_i\le t]+F(S\cup\{i\},t-\tau_i)\right],
\]

工程上先用拓扑贪心 \(p_iw_i/\tau_i\)，只有时间预算紧且 m≤8 时才开 DP。每完成一个子任务或检测到失败就重规划。该层零训练、CPU 级，是「决策规划」中性价比最高的部分。

### 1.5 为什么不做在线 RL / test-time rollout

- **在线 RL**：评测期禁止任何在线学习/适应（诚信红线）；真机通道稀缺；32 任务无对齐仿真（F14 的 sim 与赛题无直接对齐），sample efficiency 无法兑现。
- **test-time 世界模型 rollout**：WMA-0 的仿真模式（F15）每次 rollout 都是秒级成本，与 66ms/1s 级预算冲突；I7 因此裁撤，资产转数据侧。
- **结论**：本轮的 RL 只做离线价值学习；规划只做推理期候选选择；两者都不更新权重。

### 2.1 得分点回报与 return-to-go

```python
def score_rewards(detector_hits, weights):
    # detector_hits[t] = 第 t 帧新达成的得分点索引集合
    r = []
    for hits in detector_hits:
        r.append(sum(weights[j] for j in hits))
    return r

def return_to_go(r, gamma=0.99):
    G, acc = [0.0] * len(r), 0.0
    for t in reversed(range(len(r))):
        acc = r[t] + gamma * acc
        G[t] = acc
    return G

def chunk_targets(G, H):
    # chunk 起点 t 的回归目标 = 从该状态起的 return-to-go
    return G  # 与候选 chunk 的起点对齐；若用 chunk 内回报可改为 sum(r[t:t+H]) + gamma**H * G[t+H]
```

### 2.2 价值头、AWBC 与候选重排

```python
class ValueHeads(nn.Module):
    def __init__(self, latent_dim, act_dim, H):
        super().__init__()
        self.scene = nn.Linear(latent_dim, 256)
        self.state = nn.Linear(latent_dim, 256)
        self.act = nn.Linear(act_dim * H, 256)
        self.q = nn.Sequential(nn.Linear(512, 256), nn.GELU(), nn.Linear(256, 1))
        self.v = nn.Sequential(nn.Linear(256, 256), nn.GELU(), nn.Linear(256, 1))

    def q_value(self, s_latent, a_chunk):
        h = torch.cat([self.scene(s_latent), self.act(a_chunk.flatten(1))], -1)
        return self.q(h).squeeze(-1)

    def v_value(self, s_latent):
        return self.v(self.state(s_latent)).squeeze(-1)

def train_value_heads(heads, loader, vlm):
    for s, a, G in loader:
        z = vlm.encode(s).detach()
        loss = F.huber_loss(heads.q_value(z, a), G) + F.huber_loss(heads.v_value(z), G)
        loss.backward(); opt.step(); opt.zero_grad()

def awbc_loss(policy, heads, s, a, G, beta=1.0):
    with torch.no_grad():
        z = vlm.encode(s).detach()
        adv = heads.q_value(z, a) - heads.v_value(z)
        w = torch.exp(adv / beta).clamp(0.2, 5.0)
    return (w * flow_matching_loss(policy, s, a)).mean()

@torch.no_grad()
def act_with_planner(obs, policy, heads, K=3, lam=0.5):
    z = vlm.encode(obs).detach()
    cands = policy.sample_chunks(obs, k=K)          # 批量采样，一次 forward 出 K 个
    q = torch.stack([heads.q_value(z, a) for a in cands])
    unc = q.std(0) if q.shape[0] > 1 else torch.zeros_like(q[0])
    k = (q - lam * unc).argmax()
    if q[k] < Q_FLOOR or unc[k] > UNC_HI:            # 不确定性触发
        return recovery_mode(obs)                   # 短 chunk + I3/I5 先验
    return cands[k]
```

### 2.3 任务级排序与重规划

```python
def plan_order(subtasks, T_remain):
    # subtasks: [(id, w, tau, p, prereq_set)]
    done, order = set(), []
    while len(order) < len(subtasks):
        ready = [i for i in subtasks if i.prereq <= done]
        # 贪心：单位时间期望得分最大；m<=8 且时间紧时改用 bitmask DP
        pick = max(ready, key=lambda i: i.p * i.w / max(i.tau, 1e-3))
        order.append(pick); done.add(pick)
    return order

def hierarchical_act(obs, state):
    if state.task.is_multi_object and state.subtask_done_or_failed():
        state.order = plan_order(state.remaining_subtasks, state.T_remain)
    return act_with_planner(obs, state.policy, state.heads, K=state.K)
```

## 3. 实验设计（分级消融 v3）

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0-R | 奖励消融：真实得分点回报 vs 打乱回报 vs 常数回报；价值头能否复现 return-to-go 排序 | 离线（免费） | 真实回报的 Spearman 显著高于打乱/常数；否则 I10 不成立 |
| L0-V | AWBC vs BC（匹配训练预算）；优势加权 vs 质量加权；有/无 I5 负样本 | 离线（免费） | held-out flow loss 不显著变差，且 OPE/进度代理提升 |
| L0-P | 任务级排序：order-sensitive 任务 replay 上，贪心/DP vs 固定顺序/随机顺序；K=1 vs K=3 重排 | 离线 replay | 任务级排序在 order-sensitive 子集提升 ≥10%；K=3 在不超延迟下优于 K=1 |
| L1 | 2^(k-p) 析因：回报类型（得分点/进度头）× 加权方式（exp/filter）× K（1/2/3）× 任务级规划（on/off） | 离线 + 少量真机 | 主效应显著的 ≤3 个组合进入 L2 |
| L2 | 真机确认：≥2 任务 × 各 2 次；优先 PlugCharger/ZipUp/PourOutMedicine + 1 个多物体任务 | 单任务通道 | 成功率不降（字典序）且步骤分提升 ≥ 离线预测的 50%；p99 达标 |
| 门禁 | PR4：run_client 全流程 + p99 + 动作健康度；规划器降级开关 | 本地 stub | 0 拒绝动作、p99 < 40ms、K=1 回退可用 |

**关键判据**：I10 的增益必须能被「奖励消融」解释——如果打乱回报后增益消失，说明增益来自回报信号而非额外参数；如果打乱后仍有增益，说明只是正则化/容量效应，不能归因于 RL。

**首批 L2 排队计划**：①I2 共训基线 → ②I10 试点 3 任务（AWBC vs BC）→ ③I11 任务级排序（1 个多物体任务）→ ④I11 chunk 重排（1 个接触任务）→ ⑤I1/I9 既有队列。

| 项 | 配置 | 变化 |

| 训练 | 1×24GB 起步（frozen-VLM/LoRA）；价值头与主模型共用 | 价值头 <1% 参数，几乎不增成本 |

**延迟预算粗算**：数据侧 chunk=30@30Hz≈1s（F20），部署参照 15Hz/horizon16≈1.07s（F12）。若单次 chunk 前向 40ms，K=3 批量约 120ms/chunk 边界，占 1s 周期的 12%；若 serving 实际更紧，则 K=2 或 K=1 + 任务级规划。规划器永远可一键降级，不能成为单点依赖。

## 5. 本轮纸面推演与可证伪预测（未跑真机）

以下是 L0 前必须成立的预测，任一失败即调整/裁撤：

1. 在 3 个试点任务上，得分点回报的 return-to-go 在 held-out episode 上可被价值头以 Spearman≥0.5 复现；打乱回报后降至 ≈0。
2. AWBC 在匹配 BC 训练预算下，held-out flow loss 不变差（±5%），但里程碑进度代理提升 ≥3%；若 flow loss 显著变差且代理不升，说明优势加权只伤似然。
3. order-sensitive 任务（≥5 个）上，任务级贪心排序比固定顺序在 replay 中减少 ≥10% 的无效移动/超时；若不足 5 个任务对顺序敏感，I11 的任务级层降级为可选。
4. K=3 重排在延迟预算内（chunk 边界批量）比 K=1 的 OPE 高 ≥5%；若延迟超预算或增益 <2%，退回 K=1，只保留任务级规划。
5. 价值头在背景/物体外观替换（I1 反事实）下性能下降 ≤15%；若下降更大，说明视觉捷径，需加反事实训练或降低 I11 权重。
