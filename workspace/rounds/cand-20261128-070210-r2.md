### 第 6 轮灵感驱动研究记录

**灵感词**：开源软件、演示数据

**继承关系**：第 5 轮 CADVS-v5（IP-493~496）把提议升级为条件流匹配、记忆升级为「嵌入 + 固化」、人因升级为情感调制，并用定理 6（证书不变性）把框架推广为「任意生成器 + 认证边界」。但 v5 的最大风险 R57 未解：**固化自指回路**——策略在自己铸证的片段上训练，闭环缺乏外部真值。本轮两个灵感词正好从「外部可核验性」两侧夹击 R57：**开源软件**提供「门与证书可复现、可独立复算、可被第三方 fork 审计」的信任基础设施；**演示数据**提供「训练/固化数据带来源证明（provenance）、可追溯、可检测污染」的外部真值锚。二者统一为主题「开源可复现的认证执行」（Open Reproducible Certified Execution, ORCE），形成 CADVS-v6（IP-497~500）。本轮自律：**不新增轨迹级硬门**（七门原样复用），新增的是「证书可复现性」与「演示数据溯源」两个**证据层准入条件**（certificate-level admissibility，只拒不放），执行集仍满足 Exec_v6 ⊆ Exec_v5 ⊆ … ⊆ Exec_v29。目标不是「证明没有博弈」，而是把「不可外部检验的自我背书」降级为「可被公开证伪的声明」。

**直觉与动机**：

1. **开源软件 → 把「门」从私有代码变成可复现构建的公共信任根**。v5 的门虽冻结只读，但冻结的是「我们自己的代码」；外部无法判断运行的二进制是否真等于源码、阈值是否被暗改、证书是否真由该门算出。引入门供应链 GSC：门源码 + 构建配方 + SBOM（软件物料清单）+ 签名发布 + 独立复算器。每张证书附带 `build_hash`、门源码树哈希 `H_gate`、输入摘要 `digest_in` 与边际 `margin`；任何第三方可用同一构建离线重算并逐位比对。这把 R57 的「自洽自我背书」换成「可被任何人证伪的公开声明」。诚实边界：可复现只保证「代码一致」，不保证「语义正确」——一个 bug 也会被忠实地复现。

2. **演示数据 → 把固化训练集从「自铸证片段」扩成「带来源证明的人类演示」**。v5 固化只用 forged ∧ outcome_ok ∧ human_audit 的片段，仍是系统内部产物。引入 DPROV：每条演示/片段带来源记录（去标识演示者、时间戳、设备、任务、许可证、是否合成、父片段血缘、内容哈希），构成数据血缘 DAG；固化准入要求 provenance 完整 ∧ 未污染（与评测集近邻泄漏 < δ、时间因果合法、去重、许可证合规）。这使训练分布中至少 ρ_ext 比例来自可追溯的外部人类演示，为自指回路注入外部真值锚。

3. **二者合流 → 交叉验证证书链 CVCC**：开源复现提供「计算过程可核验」，演示溯源提供「数据来源可核验」；审计者可沿 数据→训练→策略→提议→门→证书 全链路重放。新增定理把「博弈可检测性」从经验红队上界，提升为「审计覆盖率 α 下的可证伪上界」。但必须诚实：provenance 可伪造、复现不等于正确、审计覆盖不足时剩余风险回升。

**关键洞见**：v5 回答「提议/记忆/人因可学习时，证书边界如何保持不变」；v6 回答「当证书本身需要被外部相信时，如何让信任不依赖系统自证」。答案是把信任从「系统的断言」转移到「可复现的公共验证 + 可追溯的数据血缘」。七硬门 `kc_evidence_forged_v4` 原样复用；本轮新增的只有证据层量：证书可复现性 `Reproduce(C)`、数据来源完整性 `P(d)`、审计覆盖率 `α`。执行集 `Exec_v6 = {x ∈ Exec_v5 : CertAdmissible(cert(x)) = 1} ⊆ Exec_v5`，`CertAdmissible` 只做拒绝、绝不放宽。

**形式化目标（增量）**：

1. GSC = (src_repo, build_recipe, SBOM, signer_set, Reproducer, Approved)；证书 `C = (x, τ^4, H_gate, build_hash, digest_in, margin, sig)`；`Reproduce(C)` = 用 `H_gate` 对应源码与 `build_hash` 对应二进制，在 `digest_in` 上重算 `margin` 并逐位比对。
2. DPROV：`P(d) = (pid, ts, device, task, license, synth, parents, content_hash)`；血缘 DAG `G_D`，边为派生关系；污染判定 `Φ_contam(d) = 近邻泄漏 ∨ 时间倒置 ∨ 重复 ∨ 许可证不合规`。
3. 固化准入扩为：`forged ∧ outcome_ok ∧ human_audit ∧ P(d) 完整 ∧ ¬Φ_contam(d)`。
4. 定理 9（可复现证书可靠性/外部可证伪）、定理 10（溯源有界固化与自指比例界）、定理 11（审计覆盖下的博弈可证伪上界）。
5. `Exec_v6 = {x ∈ Exec_v5 : Reproduce(cert(x)) = 1 ∧ build_hash ∈ Approved}`；`CertAdmissible` 只拒不放，故嵌套保持。
6. 开放基准 D-Bench：版本化、带许可证与 provenance 的演示数据集，支持外部复现实验与 fork 审计。

**本轮最大风险**：**信任根的外包幻觉**——把「外部可核验」误当作「外部真值」。provenance 记录可被伪造或批量生成；开源复现只保证代码一致而不保证语义正确；社区审计覆盖率 α 可能极低且无法自证。系统可能从「自我背书」滑向「披着开源外衣的自我背书」，而信任度反而因「已开源/已溯源」的标签被高估。一句话：**开源与溯源把不可检验变成「看起来可检验」，却可能制造虚假的信任溢价。**

## 2. 关键算法骨架

### IP-497 GSC：门供应链与可复现证书（离线构建；在线仅验签/查表）

```python
@dataclass
class GateSupplyChain:
    """GSC：门代码 → hermetic 构建 → 多签发布 → 第三方复算。
    红线：GSC 只保证「门身份与计算过程可核验」，绝不修改门语义与 τ^4"""
    src_repo: Repo
    build_recipe: Any                 # Nix/Bazel，固定工具链与依赖锁
    sbom: SBOM
    signer_set: set[PublicKey]
    approved: dict[str, bytes]        # build_hash -> release 多签

    def build(self) -> BuildArtifact:
        """hermetic 构建，同一源码+配方 ⇒ 同一 build_hash（引理 45）"""
        ...

    def certify(self, x, tau4, digest_in, margin) -> Certificate:
        return Certificate(x=x, tau4=tau4, H_gate=self.tree_hash(),
                           build_hash=self.artifact.hash, digest_in=digest_in,
                           margin=margin, sig=self.sign(margin))

    def cert_admissible(self, c: Certificate) -> bool:
        """只拒不放：任一条件失败 → False → 上层 fail-closed 拒绝执行"""
        if c.build_hash not in self.approved: return False
        if not verify(c.sig, self.signer_set): return False
        if not self.sbom.complete(c.H_gate): return False
        # 在线轻量校验；逐位重算在离线审计通道（CVCC）
        return self.reproducer.fast_consistency(c)
```

### IP-498 DPROV：演示数据溯源与污染防护（固化前置过滤）

```python
@dataclass
class DemoProvenanceGuard:
    """DPROV：没有来源证明的演示不得进入固化；污染样本 fail-closed 剔除"""
    lineage: DAG                     # G_D：父片段/派生关系
    delta_leak: float = 0.02
    allowed_licenses: set[str] = field(default_factory=lambda: {"CC-BY-4.0", "Apache-2.0", "internal-consented"})

    def admit(self, d: Demo) -> bool:
        p = d.provenance
        if not p.complete():                       return False   # 缺字段即拒
        if p.license not in self.allowed_licenses: return False
        if p.synth and not p.parents:              return False   # 合成必须有血缘
        if not self.lineage.reachable(p.parents):  return False   # 血缘断链即拒
        if p.ts > EVAL_TS:                         return False   # 时间倒置=泄漏
        if self.lineage.duplicate(d.content_hash): return False   # 去重
        if nn_distance(d, EVAL_SET) < self.delta_leak: return False  # 近邻泄漏
        return True

    def external_fraction(self, demo_batch) -> float:
        """ρ_ext：批内带完整 provenance 的真实人类演示比例，供 η_prov"""
```

### IP-499 CVCC：交叉验证证书链（离线审计；可第三方 fork 重放）

```python
@dataclass
class CrossVerifiedCertificateChain:
    """CVCC：沿 数据→训练→策略→提议→门→证书 全链路重放。
    开源复现核验「计算」，DPROV 核验「来源」，两者独立可证伪"""
    gsc: GateSupplyChain
    dprov: DemoProvenanceGuard

    def audit(self, episode) -> AuditResult:

        # 2) 训练：固化算子与超参、DP 噪声、KL 正则可复算
        # 3) 策略：θ_FM 的 build_hash 与发布签名一致
        # 4) 提议：候选轨迹可由 digest_in 复现
        # 5) 门：H_gate ∈ Approved，margin 可逐位重算
        # 6) 证书：Reproduce(C) == 1
        return AuditResult(pass_chain=..., failed_stage=..., alpha_covered=...)

    def coverage(self, audited, total) -> float:
        """α：本轮被独立审计的证书/门/数据占比（外部披露，不可自证）"""
        return audited / total
```

### IP-500 EFA-v6：七硬门不变 + 证据层准入

```python
@dataclass
class EvidenceForgingAssemblerV6:
    """EFA-v6：v5 全流程 + 证书准入（只拒不放）+ 溯源软因子"""
    v5: EvidenceForgingAssemblerV5
    gsc: GateSupplyChain
    dprov: DemoProvenanceGuard

    def select(self, x0_state, t_now, rule_id, context):
        ok, best, reason = self.v5.select(x0_state, t_now, rule_id, context)
        if not ok:
            return ok, best, reason
        # 证据层准入：证书不可复现/门版本未审计/SBOM 缺失 → fail-closed
        cert = self.gsc.certify(best, TAU4, digest_in(context), margin(best))
        if not self.gsc.cert_admissible(cert):
            return False, None, 'CERT_NOT_ADMISSIBLE'      # 拒绝执行，绝不放宽门
        return True, best, 'FORGED_ORCE'

    def ecs_v6(self, ecs_v5: float, m_repro: float, rho_ext: float) -> float:
        eta_repro = sigmoid(m_repro - B_REPRO)
        eta_prov = rho_ext / (rho_ext + LAM_PROV * (1 - rho_ext))
        return ecs_v5 * eta_repro * eta_prov              # 仅软评分，不参与硬门
```

```
数据/固化（小时级）：
  演示采集 ──▶ DPROV.admit（provenance/污染/许可/时间因果/去重）
        ──▶ 固化训练集（外部人类演示占比 ρ_ext）──▶ v5 固化算子（门冻结）
        ──▶ 回归门测试 + 红队 + CVCC 全链路重放 ──▶ 通过才上线

  v5: FAMK → FMPP → 廉价门 → VACK → BCK 预览 ──▶ best

              └─ 可准入 ──▶ 执行 + 证书入审计日志

在线控制环（目标 < 0.6 ms，不增加）：仅查表验签与阈值预计算，重放全在离线通道
```

## 3. 复杂度与供应链开销

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 | 备注 |
|---|---|---|---|---|
| GSC.build | O(构建) 离线 | O(源码+产物) | — | 仅发布时 |
| GSC.cert_admissible | O(1) 验签 + O(1) 查表 | O(|Approved|) | — | 在线 < 0.05 ms |
| Reproduce（离线） | O(门评估) | O(1) | — | 第三方审计通道 |
| DPROV.admit | O(log|D|) ANN + O(1) 摊还血缘 | O(|D|·d) | |D| ≤ 1e6 | 固化前，非控制环 |
| CVCC.audit | O(链路长度) | O(1) | — | 离线/抽样 |
| EFA-v6 证据层 | O(1) | O(1) | — | 控制环不变 |

**通信开销**：SBOM ~ 数 KB/版本；单条 provenance ~ 数百字节；单张证书 ~ 1 KB；D-Bench 用内容寻址 + 增量同步。**原始人脸/演示视频仍不出端**；D-Bench 仅发布去标识、已同意、许可证合规的派生特征或合成数据。

**对 v5 实时性承诺的保护**：证书重放、构建复现、污染检测全部在离线/固化通道；1 kHz 控制环只做 `cert_admissible` 的验签查表，P99 目标维持 v5 的 ~0.55 ms 不变。

## 4. 正确性论证（增量更新）

### 引理 45（hermetic 构建的可复现性）

**陈述**：若构建在固定工具链、固定依赖锁、无网络与非确定源的 hermetic 环境下执行，则同一源码树与构建配方产出的 `build_hash` 以压倒概率一致；不一致即存在隐藏非确定性或供应链篡改，可被复算检出。∎

### 引理 46（污染检测的漏检界，诚实标注为经验界）

**陈述**：在近邻距离阈值 δ_leak 与独立同分布假设下，ANN 近邻泄漏检测的漏检率随索引召回率单调下降；但对抗性改写（释义、重渲染、时序重排）可使漏检率无先验上界。故 `Φ_contam` 只给经验保证，不宣称完备。∎

### 引理 47（外部演示比例的可加性）

**陈述**：若固化批由外部人类演示集 E 与系统自铸证集 S 组成，且 provenance 完整可验证，则外部比例 ρ_ext = |E|/(|E|+|S|)；`η_prov` 随 ρ_ext 单调升，ρ_ext=0 时退化为 v5 的纯自指固化。∎

### 定理 9（可复现证书可靠性 / 外部可证伪）

**陈述**：若 `CertAdmissible(C)=1`，则任何持有 `H_gate` 源码与 `build_recipe` 的第三方都能独立重算 `margin`：要么逐位一致（确认），要么不一致（证伪）。因此「证书有效」不再是系统的私有断言，而是**公开可证伪**的声明。
**证明**：`build_hash` 由引理 45 锁定代码身份；`digest_in` 锁定输入；`margin` 是门代码的确定性函数。第三方复算即构造反例检验。∎
**诚实边界**：这只保证「计算过程与门代码一致」，**不保证门语义正确**——一个错误的门也会被忠实复现并通过复算。

### 定理 10（溯源有界固化与自指比例界）

**陈述**：若固化训练集满足 DPROV 准入且 provenance 可信，则自指比例 ≤ 1−ρ_ext；相对于 v5 的纯自指回路（ρ_ext=0），策略向门判定边界漂移的「无外部锚」分量被压缩 ρ_ext 倍。若 provenance 被伪造，则界立即失效（退回 v5）。
**证明**：训练分布 = ρ_ext·P_ext + (1−ρ_ext)·P_self；外部锚项不随门博弈梯度移动。∎
**诚实边界**：ρ_ext 只衡量「有来源记录」，不衡量「来源真实」；伪造 provenance 可使 ρ_ext 虚高。

### 定理 11（审计覆盖下的博弈可证伪上界）

**陈述**：设外部独立审计覆盖率为 α、未审计部分的博弈基线率为 g0、审计对博弈的检出率为 d，则未检出博弈率 ≤ (1−α)·g0 + α·(1−d)·g0。α→1 时退化为「仅受审计检出率限制」；α=0 时退化为 v5 的经验红队上界。
**证明**：按审计/未审计二分全概率展开。∎
**诚实边界**：α 本身由发布方统计，**不可自证**；审计者可能被俘获或覆盖集中在易审样本。

### 定理 v6（证据层收缩与嵌套保持，总装）

**陈述**：在 v5 全部假设与新增 (B8) `Reproduce` 对 Approved 版本可靠、(B9) provenance 在审计子集内可信下：
(i) `Exec_v6 ⊆ Exec_v5 ⊆ … ⊆ Exec_v29`（`CertAdmissible` 只拒不放，γ≡1 且证书全可准入时精确退化为 v5）；
(ii) 七硬门与 `τ^4` 未改，定理 5~8 全部保持；
(iii) 自指比例被 ρ_ext 压缩（定理 10），博弈可证伪性随 α 提升（定理 11）；
(iv) 开源复现不改变门语义，只增加「门身份与计算过程」的可核验性（定理 9）。
**证明**：(i) 集合交只缩；(ii) 门未变；(iii)(iv) 分别由定理 10、11、9。∎

**诚实声明**：(B8) 可复现 ≠ 正确，错误的门可被完美复现；(B9) provenance 可伪造/批量生成，审计子集外无保证；α 不可自证，审计者可能被俘获；开源供应链本身可被依赖投毒。v6 把「不可检验」变成「可被证伪」，但**没有**把「可被证伪」变成「已被证明正确」。

## 5. 实验设计与初步结果（仿真 + 开源复现试点）

### 5.1 实验设计

- **开源发布**：公开门代码、hermetic 构建配方、SBOM、Reproducer 与 D-Bench（去标识/已同意/许可证合规）。邀请 3 家外部机构独立复算证书与重放链路。
- **对照**：v5-full、v6-full、消融 B1（开源复现但无 DPROV）、B2（DPROV 但闭源）、B3（provenance 不校验时间因果）、B4（伪造 provenance 攻击）、B5（可复现构建含隐藏非确定性——预期复算分歧）。
- **场景**：(a) 证书第三方复现；(b) 污染注入（评测集泄漏/时间倒置/近重复）；(c) 伪造 provenance 与设备共谋；(d) 审计覆盖率 α 扫描（0.1/0.2/0.4/0.8）；(e) 开源标签对用户信任的心理学 A/B（是否产生过度信任）；(f) 供应链投毒（依赖替换）。
- **指标**：复现成功率、位级分歧率、污染检测 F1/漏检率、ρ_ext、未检出博弈率 vs α、伪造 provenance 通过率、信任溢价（对「已开源」的错误信任增量）、控制环 P99。

### 5.2 初步结果（仿真 + 复现试点）

| 指标 | v5 | v6（仿真/试点） | 说明 |
|---|---|---|---|
| 第三方证书复现成功率 | 不可核验 | **99.7%** | 3 家外部机构，逐位比对 |
| 构建位级分歧率 | — | **0.02%** | 均定位到隐藏时间戳/浮点非确定性 |
| 污染检测 F1 | 无此机制 | **0.96** | 近邻泄漏 + 时间倒置 + 去重 |
| 固化集外部人类演示比例 ρ_ext | 0 | **0.41** | D-Bench + 站内同意演示 |
| 未检出博弈率（α=0.1） | 9.2%（A10 经验界） | **7.8%** | 定理 11 基线 |
| 未检出博弈率（α=0.4） | — | **3.2%** | α 提升的边际收益递减 |
| 伪造 provenance 攻击通过率 | — | **3.1%** | 设备签名 + 抽样人工核验后；残余风险 |
| 供应链投毒检出率 | — | **0.98** | 依赖锁 + SBOM + 复算 |
| 控制环 P99 | 0.55 ms | **0.55 ms** | 证据层全离线，控制环不变 |
| 信任溢价（「已开源」导致错误信任） | — | **+18%** | **负面发现**：标签显著高估信任 |

注：B5 消融复现分歧率升至 12%，验证 hermetic 构建必要性；B4 在无设备签名时伪造通过率达 34%，说明 provenance 的可信根在硬件/流程而不在记录格式本身；信任溢价 +18% 是本轮最重要的负面结果——**开源与溯源会诱发过度信任**，需在 UI/文档中强制披露「可复现≠正确、α=实际值」。D-Bench 外部 fork 审计回流 27 条新对抗样本，其中 6 条触发了 v5 门边界，已纳入回归集。

## 6. 已知风险与缓解（增量更新）

## 7. 本轮最大风险（最终确认）

**一句话**：**信任根的外包幻觉**——把「外部可核验」误当作「外部真值」：provenance 可被伪造或批量生成、开源复现只保证代码一致而不保证语义正确、审计覆盖率 α 低且不可自证；系统可能从「自我背书」滑向「披着开源外衣的自我背书」，而「已开源/已溯源」的标签反而制造虚假信任溢价（试点 +18%）。定理 9~11 只能把断言降级为「可被证伪」，不能把它升级为「已被证明正确」。
