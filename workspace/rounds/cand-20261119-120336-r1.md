# 第 16 轮（新灵感循环；本轮灵感：「语音交互」×「用户测试」）

> **基线**：第 15 轮 MetricVoiceGauge-NCD-HUTDH-v15（SCD/DSD/DCA/EDC；定义 607–626；引理 125–130；实验 E661–E670）。
> 本轮纪律：**语音只收窄不扩权 + 用户级共形 + 人环证书路由**。不推倒 v15：v13 的 AIO/CPD/DDL/RTCR、v15 的 SCD/DSD/DCA/EDC、v12 的 USG/TGC/BAA/GAGP/UC、v11 的 HAS/HCC/HATD/HDT、v10 的 NGE/DSL/CC/CWM/CAE/NCP、v9 的 AC/MW/ID、v8 的 DA/SPR/Cal 与九不变式全部保留。三个新组件——VGC（语音接地证书）、UCC（用户级共形校准，含 UTL 用户测试账本）、HLR（人环证书路由器）——一律以**中立元**接入，失效即严格退回 v15（引理 133），再沿 v15 退化链退回 v14/v13/v12/v11/v10/v9/v8/v7/v6。本轮只做三件事：把"语音"从命令通道改写为**约束/偏好通道**、把"用户测试"从满意度评估改写为**用户级共形校准与信任校准审计**、把二者合成"语音提议—证书裁决—澄清回退"的人环闭环。

## 0. 直觉与动机

**灵感 1（语音交互 → 语音是约束与偏好的通道，不是权限的来源）**
直觉：语音是家庭/服务机器人最自然的入口，但它同时是最不可证的入口。ASR 的转写置信度与语义接地置信度是两回事：一句话可以被"听得很清楚"却"理解得很含糊"——"把那个拿过来"在转写层面 0.99，在指代层面可能对应三个物体。若把语音直接当命令执行，系统就在最薄的人类意图边界上引入了一个不可验证的跳跃。核心创新：**语音接地证书（Voice Grounding Certificate, VGC）**。它把每句话压成一个候选动作集 `A_v(u)` 与一个单侧下界 `p_g(u) ≤ P(a*(u) ∈ A_v(u))`，并要求 `A_v(u) ⊆ Exec_v15`：语音只能**收窄**已认证的执行集，不能新增任何授权。只有"高置信 + 单例 + 余量足够"时才自主执行；否则输出**澄清动作**（复述、菜单、指认），而澄清本身永远是认证安全动作。关键反直觉点：**安全语音接口的优化目标不是"听懂更多"，而是"更准地知道自己没听懂"**；沉默、复述和拒绝解析应当被当作一等安全输出，而不是交互失败。紧急"停"则是唯一的单调例外——它只会把执行集收缩到回退，因此可以无条件接受。

**灵感 2（用户测试 → 用户级共形与信任校准，而不是满意度打分）**
直觉：现有安全证书都默认样本可交换，但语音数据的最小相关单元是**用户**，不是语句。同一个人的口音、语速、用词习惯会让他的句子高度相关；若按语句做共形校准，等于把"一个用户的 k 句话"当成 k 个独立证据，覆盖率会被系统性高估，换一个新用户就失效。核心创新：**用户级共形校准（User-Level Conformal Calibration, UCC）+ 用户测试账本（User-Test Ledger, UTL）**。UCC 以用户为可交换单位、以"该用户语句级接地失败率"为非一致性分数，给出新用户的单侧覆盖保证；UTL 把每次用户测试失败分成四类——证书违规、覆盖缺口、偏好不符、ASR 错误——只有前两类允许进入重校准，而且只能**收紧**阈值或**补覆盖**，不得因为"用户不满意"而放宽安全边界。关键反直觉点：**用户满意度与信任都不是目标，信任校准才是**。一个流畅的语音接口会提高过度信任；若用户以为机器人"什么都懂"，那么再高的满意度也是安全负债。用户测试要测的是 `Δ_trust=|用户主观可靠性−证书下界|`，并分层覆盖口音、年龄、性别、噪声环境等群体。

**灵感 3（语音×用户测试 → 人环证书路由与澄清经济）**
直觉：语音给出的其实不是"要做哪个动作"，而是"我更想要什么"；证书给出的才是"哪些可以做"。于是正确的合成不是"语音命令 → 执行"，而是"语音偏好 → 在已认证阶梯里排序 → 在时间预算内选档"。核心创新：**人环证书路由器（Human-in-the-Loop Certificate Router, HLR）**。它复用 v13 的时限阶梯与 v15 的扩散档位：语音只改变档位的**偏好顺序**，证书与剩余时间决定**可行性**；当语音接地集与所有可行档位无交集时，路由器必须在"澄清"与"回退"之间按显式代价选择，而不是猜一个最近邻动作。澄清是一种有预算的稀缺资源：每次追问消耗用户注意力 `B_ask`，也消耗本帧时间；因此路由器要解的是"在 `B_time`、`B_ask`、信任校准约束下最大化已认证效用"的在线问题。关键反直觉点：**最好的语音交互有时是拒绝解析**；一个把"我不确定"说清楚的机器人，比一个总能给出流畅答案的机器人更可证。

**三者如何统一**
统一为 **v15 之上的通信/人因层**：v15 回答"在毫秒与数据支撑内能安全实现多少"（`Exec_v15`），v16 回答"这些可实现的决策里，哪一些确实对应用户的意图，且用户能正确理解系统的可靠性"（`Exec_v16`）。VGC 是**收窄算子**（语音只做交），UCC 是**证据单元修正**（把校准单位从语句提升到用户），HLR 是**偏好—约束分离器**（语音排序、证书裁决），VSC 是**漂移塌缩器**（检测到新口音/新环境就转入确认模式）。共享状态 `ζ_voice=(A_v, p_g, q_u, U_u, B_time, B_ask, rung, mode, Δ_trust)`。**VGC 回答"这句话可能指哪些已认证动作"，UCC 回答"这个保证对新用户还成立吗"，HLR 回答"现在该执行、澄清还是回退"**。三者不是三个交互补丁，而是"接地—校准—路由"的人环链，且 `Exec_v16⊆Exec_v15`。

## 1. 研究问题（本轮升级版）

- **Q1（语音的可证接地）**：如何把自然语言命令压成"候选集 + 单侧覆盖下界"，使 `A_v(u)⊆Exec_v15` 且"执行即落在用户意图内"有共形保证？指代接地（哪个物体）与意图接地（做什么）如何分别认证并合成？ASR 置信度、语义置信度与共形阈值如何避免互相冒充？
- **Q2（用户级校准与测试账本）**：以用户为交换单位时，需要多少用户、每用户多少语句才能给出可用的覆盖保证？用户内相关如何修正有效样本量？用户测试的四类失败如何分类、入账、只收紧不放宽？分层群体覆盖（口音/年龄/性别/噪声）如何与总体保证同时成立？
- **Q3（人环路由与澄清经济）**：语音偏好、证书约束、时间预算、澄清预算四者如何在线联合优化？澄清与回退的代价如何显式建模，避免"为了不追问而猜"？信任校准 `Δ_trust` 如何进入目标函数而不退化为满意度最大化？
- **Q4（与 v15 的兼容与活性）**：语音层是否会绕过 v15 的 SCD/DSD/DCA/EDC 与 v12 的四重证书？用户级保证在用户分布漂移（新口音、新环境、被胁迫用户）下如何失效与塌缩？新增模块能否守住 50Hz/p99≤22ms，并严格退回 v15？

## 2. 设计原则（在 P22–P24 基础上新增 P25–P27）

**P25 语音只收窄律（Voice Narrows, Never Grants）**
语音接地集必须在任何证书之前先与已认证执行集求交：`A_v(u) ⊆ Exec_v15`，且 `Exec_v16 ⊆ Exec_v15`。语音不得新增技能、放宽阈值、绕过澄清或把"用户说了"当作安全证据。紧急停止是唯一允许的单调收缩：它只能把执行集降到认证回退。

**P26 用户级证据律（The User Is the Exchangeable Unit）**
任何语音覆盖保证的校准单位是用户而非语句；必须报告用户内相关下的有效样本量 `n_eff` 与用户级阈值 `q_u`。用户测试失败只能触发收紧或补覆盖；不得以满意度、信任度或任务完成率为由放宽安全证书。分层群体的覆盖率必须逐层报告，不得用总体平均掩盖少数群体缺口。

**P27 信任校准优先律（Calibrate Trust, Not Satisfaction）**
交互目标函数必须包含信任校准项 `Δ_trust`，并要求系统主动暴露其证书边界（"我能做/不能做/不确定"）。禁止以"减少追问"为唯一优化目标；澄清预算 `B_ask` 与实时预算 `B_time` 都是稀缺资源，但都不得挤占安全余量。检测到语音/用户分布漂移时，必须转入确认模式或安全塌缩，而不是继续用旧阈值"赌"。

## 3. 与基线的接口（如何退化）

- VGC 失效 ⇒ `A_v(u)≡A`、`p_g≡1`，语音退化为无约束文本日志，执行完全由 v15 决定，**等价 v15**；
- UCC 失效 ⇒ 语句级校准 + `q_u≡1`，只保留经验估计，**等价"v15 + 朴素语音前端"**；
- HLR 失效 ⇒ 由 v15 的 DSD/RTCR 固定顺序选档，语音仅作事后标注，**等价 v15 调度路径**；
- VSC 失效 ⇒ 不检测漂移、不转确认模式，**等价"v15 + VGC + UCC"**；
- 四者全失效 ⇒ MetricVoiceGauge-NCD-HUTDH-v15，再沿 v15 退化链退回 v14/v13/v12/v11/v10/v9/v8/v7/v6；
- **安全继承**：VGC 只做交，UCC 只改证据单元，HLR 只做偏好排序与选档，VSC 只做塌缩。四端口均不能新增授权或放宽任何阈值；`Exec_v16⊆Exec_v15` 由引理 131 保证。

## 4. 预期贡献

1. **可证语音接地**：把"语音命令"改写为"候选集 + 单侧覆盖下界 + 澄清回退"，给出 `A_v(u)⊆Exec_v15` 的收窄保证，解决"听得清但理解含糊"的结构性风险；
2. **用户级共形校准与用户测试账本**：把语音覆盖保证的交换单位从语句提升到用户，给出用户内相关下的有效样本量修正与分层群体覆盖，填补"按语句校准在换用户时失效"的空白；
3. **人环证书路由与澄清经济**：把语音偏好、证书约束、时间预算、澄清预算与信任校准统一成一个在线路由问题，使系统在不确定时选择"问"而不是"猜"；
4. **通信层—安全层分离**：v15 管"能安全实现什么"，v16 管"这是不是用户要的、用户是否理解"，用 `Exec_v16⊆Exec_v15` 把交互与安全解耦；E671–E682 覆盖接地覆盖、用户级有效性、信任校准、漂移塌缩、消融与端到端用户研究。

## 5. 本轮最大风险

**一句话**：用户级共形保证只对"与校准用户同分布的新用户"成立；一旦部署用户进入新的口音/环境/胁迫场景，VGC 的接地集与 UCC 的覆盖率会同时失效，而 HLR 为压低澄清负担会优先选择高置信单一解释——最终在"每句话都被正确转写、每个用户都在覆盖阈值内、每次执行都在证书集内"的表象下，执行了一个证书允许、用户测试背书、却从未被用户要求的动作，即**合规的、被用户背书的、却绝对违背意图的决定**。

# IP-402 Voice Grounding Certificate：把语音压成只收窄的候选集
class VoiceGroundingCertificate:
    def __init__(self, grounder, cert_v15, alpha_g=0.05):
        self.grounder = grounder        # 指代 + 意图接地器，返回 {a: score}
        self.cert_v15 = cert_v15        # v15 的 Exec 查询接口
        self.alpha_g = alpha_g
        self.q_g = None                 # 由 UCC 校准后写入

    def ground(self, u):
        # 1. 解析候选及得分；指代与意图分别打分后合成
        scores = self.grounder.score(u)                 # dict[a] -> [0,1]
        # 2. 先与 v15 已认证集求交：语音只能收窄
        allowed = {a: s for a, s in scores.items() if self.cert_v15.allows(a)}
        if not allowed:
            return frozenset(), 0.0, "no_certified_intersection"
        # 3. 取不低于校准阈值的候选，形成候选集
        tau = self.grounder.threshold(u)
        A_v = frozenset(a for a, s in allowed.items() if s >= tau)
        if not A_v:
            A_v = frozenset([max(allowed, key=allowed.get)])
        # 4. 单侧下界：非一致性分数落在用户级阈值内才给保证
        p_g = self._conformal_lower(allowed, A_v)
        return A_v, p_g, "ok"

    def _conformal_lower(self, allowed, A_v):
        if self.q_g is None:
            return 0.0
        margin = min(allowed[a] for a in A_v)
        # 保守的 0/1 覆盖证书：过阈值给 1−α_g，否则给 0
        return 1.0 - self.alpha_g if margin >= self.q_g else 0.0

    def is_singleton_confident(self, A_v, p_g):
        return len(A_v) == 1 and p_g >= 1.0 - self.alpha_g


# IP-403 User-Level Conformal Calibrator：以用户为交换单位
class UserLevelConformalCalibrator:
    def __init__(self, alpha_u=0.05):
        self.alpha_u = alpha_u
        self.user_scores = []
        self.q_u = None

    def per_user_score(self, records):
        # records: 同一用户的 [(a_star, A_v)]
        if not records:
            return 0.0
        fails = sum(1 for a_star, A_v in records if a_star not in A_v)
        return fails / len(records)

    def fit(self, users):
        # users: {user_id: [(a_star, A_v), ...]}；用户为可交换单位
        self.user_scores = sorted(self.per_user_score(r) for r in users.values())
        n = len(self.user_scores)
        if n == 0:
            self.q_u = 1.0
            return self.q_u
        k = int(np.ceil((1 - self.alpha_u) * (n + 1))) - 1
        self.q_u = self.user_scores[k] if k < n else 1.0
        return self.q_u

    def effective_sample_size(self, k_utt, rho):
        # 用户内相关 rho 下，k 条语句的有效样本量
        if k_utt <= 1:
            return float(k_utt)
        return k_utt / (1.0 + (k_utt - 1) * rho)

    def accept_user(self, score):
        return self.q_u is not None and score <= self.q_u


# IP-403b User-Test Ledger：失败分类入账，只收紧不放宽
class UserTestLedger:
    CLASSES = ("cert_violation", "coverage_gap",
               "preference_mismatch", "asr_error", "none")

    def __init__(self):
        self.entries = []

    def record(self, sid, uid, u, a_star, A_v, p_g, outcome):
        cls = self._classify(a_star, A_v, outcome)
        self.entries.append(dict(sid=sid, uid=uid, u=u, a_star=a_star,
                                 A_v=A_v, p_g=p_g, outcome=outcome, cls=cls))
        return cls

    def _classify(self, a_star, A_v, outcome):
        if outcome == "unsafe_execute":
            return "cert_violation"
        if a_star not in A_v:
            return "coverage_gap"
        if outcome == "user_rejected_safe_action":
            return "preference_mismatch"
        if outcome == "asr_mismatch":
            return "asr_error"
        return "none"

    def tightening_actions(self):
        # 只有前两类允许改变证书；其余只记录，不放宽阈值
        acts = []
        for e in self.entries:
            if e["cls"] == "cert_violation":
                acts.append(("tighten", e["sid"]))
            elif e["cls"] == "coverage_gap":
                acts.append(("add_coverage", e["sid"]))
        return acts

class HumanInTheLoopRouter:
    def __init__(self, ladder_v15, cert_v15, vgc, ucc,
                 budget_time, budget_ask,
                 c_ask=1.0, c_fallback=5.0, c_false_accept=1000.0):
        self.ladder = ladder_v15        # 单调嵌套的认证档位 Acc_0..Acc_m
        self.cert = cert_v15
        self.vgc = vgc
        self.ucc = ucc
        self.B_time = budget_time
        self.B_ask = budget_ask
        self.c_ask, self.c_fallback = c_ask, c_fallback
        self.c_fa = c_false_accept
        self.asked = 0

    def route(self, u, obs, user_score, remaining_time, drift=False):
        A_v, p_g, status = self.vgc.ground(u)
        if status != "ok":
            return self._clarify_or_fallback(A_v, status)
        if drift or not self.ucc.accept_user(user_score):
            return ("confirm", A_v, "shift")
        # 语音只给偏好；证书与时间决定可行档
        feasible = []
        for r, Acc_r in enumerate(self.ladder):
            inter = A_v & Acc_r
            if inter:
                feasible.append((r, inter))
        if not feasible:
            return self._clarify_or_fallback(A_v, "no_intersection")
        # 选"负担得起的最富档"；档位由 v15 的单调阶梯给出
        for r, inter in sorted(feasible, key=lambda t: -t[0]):
            if self.cert.wcet(r) <= remaining_time:
                return self._decide(inter, p_g, r)
        return self._clarify_or_fallback(A_v, "timeout")

    def _decide(self, inter, p_g, r):
        if len(inter) == 1 and p_g >= 1.0 - self.vgc.alpha_g:
            return ("execute", next(iter(inter)), r)
        return self._clarify_or_fallback(inter, "ambiguous")

    def _clarify_or_fallback(self, payload, reason):
        # 澄清是认证安全动作，但有 B_ask 预算；超时不再追问
        if self.asked < self.B_ask and reason != "timeout":
            self.asked += 1
            return ("clarify", payload, reason)
        return ("fallback", None, reason)


# IP-405 Voice Shift & Confirmation Controller：漂移塌缩
class VoiceShiftController:
    def __init__(self, mu_asr, mu_env, eta_asr=0.5, eta_env=0.5):
        self.mu_asr, self.mu_env = mu_asr, mu_env
        self.eta_asr, self.eta_env = eta_asr, eta_env
        self.mode = "normal"

    def update(self, asr_features, env_features):
        d_asr = float(np.linalg.norm(asr_features - self.mu_asr))
        d_env = float(np.linalg.norm(env_features - self.mu_env))
        if d_asr > self.eta_asr and d_env > self.eta_env:
            self.mode = "collapse"
        elif d_asr > self.eta_asr or d_env > self.eta_env:
            self.mode = "confirm_only"
        else:
            self.mode = "normal"
        return self.mode

## 2. 关键定义（627–640）

**定义 627（语句、意图与接地器）** 语句 `u∈U`，用户真实意图 `a*(u)∈A`，接地器输出 `g(u)={(a,s_a)}`，`s_a∈[0,1]` 为指代与意图合成得分。

**定义 628（语音接地证书 VGC）** 三元组 `(A_v(u),p_g(u),status)`，要求 `A_v(u)⊆Exec_v15` 且 `p_g(u)≤P(a*(u)∈A_v(u)|u)`；有效当 `status=ok` 且 `p_g(u)≥1−α_g`，否则必须走澄清或回退。

**定义 629（语音包络）** `V(u)=A_v(u)∩A_confirm(u)`；无确认模式时 `A_confirm=A`，确认模式时 `A_confirm` 为用户从认证菜单中显式选择的子集。

**定义 630（用户级非一致性）** 用户 i 的 `k_i` 条语句，`S_i=(1/k_i)Σ_j 1[a*(u_{ij})∉A_v(u_{ij})]`。

**定义 631（用户级阈值）** 将 `S_(1)≤…≤S_(n)` 排序，`q_u=S_(⌈(1−α_u)(n+1)⌉)`；下标越界时取 `q_u=1`。

**定义 632（用户测试账本条目）** `e=(sid,uid,u,a*,A_v,p_g,outcome,cls)`，`cls∈{cert_violation,coverage_gap,preference_mismatch,asr_error,none}`。

**定义 633（信任校准间隙）** `Δ_trust=|r̂_user−r_cert|`，`r̂_user` 为用户主观或行为估计的可靠性，`r_cert` 为证书下界。

**定义 634（澄清动作与预算）** `a_ask∈Exec` 恒真；每任务至多 `B_ask` 次澄清；澄清代价 `c_ask`，回退代价 `c_fallback`，假接受代价 `c_fa`，且 `c_fa≫c_fallback≫c_ask`。

**定义 635（HLR 状态）** `ζ_voice=(A_v,p_g,q_u,U_u,B_time,B_ask,rung,mode,Δ_trust)`。

**定义 636（语音漂移）** 统计量 `d_v=d_ASR+d_env`，阈值 `η_v=η_asr+η_env`；`mode∈{normal,confirm_only,collapse}`。

**定义 637（通信证书）** `CC(u)=(p_g≥1−α_g)∧(S_uid≤q_u)∧(Δ_trust≤δ_t)∧(d_v≤η_v)`，与 v15 全部证书合取，不得替代任一项。

**定义 638（用户覆盖）** 分层集合 `G`（口音/年龄/性别/噪声），`ρ_user=|G_cal∩G_deploy|/|G_deploy|`。

**定义 639（确认模式）** `Acc_confirm={a: 用户在认证菜单中显式选择 a}`；确认只能从 `A_v∩Acc_r` 中选，不能新增。

**定义 640（v16 执行集）** `Exec_v16=⋃_{r=0..m}(Acc_r∩V(u))`，其中 `Acc_0⊆…⊆Acc_m⊆Exec_v15` 继承 v15 单调阶梯。

## 3. 推导

**引理 131（语音收窄）** 对任意语句 `u`，`Exec_v16⊆Exec_v15`。证明：每个 `Acc_r⊆Exec_v15`，且 `V(u)⊆A_v(u)⊆Exec_v15`，有限交仍落在 `Exec_v15` 内，任意并仍落在其中。∎ 推论：**VGC 的任何错误（错接地、错合并、错置信）最多导致假拒绝或澄清，绝不会新增授权**；安全下界完全由 v15 承担。

**引理 132（用户级共形有效性）** 若校准用户与部署新用户可交换，且 `S_i` 如定义 630，则由定义 631 的 `q_u` 有 `P(S_{n+1}≤q_u)≥1−α_u`。证明：以用户为交换单位、以 `S_i` 为非一致性分数，标准分裂共形次序统计量给出该覆盖；用户内相关性被折叠进每用户单一分数，不破坏用户间可交换性。∎ 推论：**若错误地按语句校准**，在用户内相关 `ρ>0`、每用户 `k` 句时，有效样本量约为 `n_eff=k/(1+(k−1)ρ)`；把 `n_u·k` 当作独立样本会高估证据量，名义 `1−α` 覆盖最多乐观 `O(√((1+(k−1)ρ)/(n_u k)))`。

**引理 133（中立元退化）** 若 VGC 返回 `A_v=A`、`p_g=1`，UCC 返回 `q_u=1`，HLR 采用 v15 固定调度，VSC 恒返回 `normal`，则 `Exec_v16=Exec_v15`。证明：逐项代入定义 628–640，交集与偏好排序均退化为恒等，执行集等于 v15。∎ 推论：**通信层可整体拔除而不影响既有安全证书**，这给出严格的回退接口。

**引理 134（歧义—澄清权衡）** 设假接受代价 `c_fa`、澄清代价 `c_ask`、回退代价 `c_fb`，且 `c_fa≫c_fb≫c_ask`。在"候选集非单例或 `p_g<1−α_g` 时必须澄清"的策略下，期望代价不高于任何"强行从多候选里选一个执行"的策略，且假接受率 ≤ `α_g`。证明：多候选时强行选择，其假接受概率至少为候选后验中非意图部分的质量，代价按 `c_fa` 放大；澄清把该风险转移为有界 `c_ask`，在给定代价序下占优。∎ 推论：**澄清不是交互失败，而是风险转移**；把"减少追问"当作主目标会把风险推回假接受。

**引理 135（漂移下的确认塌缩）** 当 `mode∈{confirm_only,collapse}` 时，任何被执行动作要么属于 `A_v∩Acc_confirm`，要么是认证回退，故物理安全继承 v15；活动性损失满足 `P(无可执行认证动作)≤P(shift)+P(B_ask 耗尽)+P(confirm 超时)`。证明：确认模式只允许显式选择已认证子集；塌缩模式直接执行回退。三种损失事件覆盖所有无可执行路径。∎ 推论：**漂移时用确认/回退买重校准时间，而不是用旧阈值赌**。

**引理 136（信任校准三难）** 对任何隐藏证书边界、只展示"成功/失败"的语音接口，澄清负担、假接受率与信任间隙三者不能同时小：若把澄清压到很低，则要么假接受率 ≥ `α_g`，要么 `Δ_trust` 随流畅度上升而超过 `δ_t`。证明要点：用户对可靠性的估计 `r̂_user` 只能从接口信号更新；当接口不暴露"不确定"信号时，`r̂_user` 在模糊质量上收敛到观测成功率，而 `r_cert` 只覆盖可证部分，二者之差在模糊质量上不可消除。∎ 推论：**显式证书披露不是可选项**；"用户很满意"不能替代信任校准。

**引理 137（用户测试到部署的迁移界）** 记 `R_deploy`、`R_test` 分别为部署与用户测试风险，则 `R_deploy≤R_test+U_u+ε_n+Δ_shift`，其中 `U_u=1−ρ_user` 为用户覆盖缺口，`ε_n` 为有限用户样本误差，`Δ_shift` 为部署—测试分布漂移项。证明：风险三角不等式分解为"测试内风险 + 覆盖缺口 + 采样误差 + 漂移项"；用户级共形只保证同分布新用户。∎ 推论：**用户测试必须分层**；否则 `U_u` 会主导迁移界，总体平均值会掩盖少数群体缺口。

## 7. 已知风险与失效模式

1. **ASR 置信度冒充接地置信度**：转写很自信但语义含糊，`p_g` 若直接复用 ASR 分数会虚高。缓解：指代/意图分开校准、强制候选集、低余量必澄清。
2. **用户内相关破坏共形覆盖**：同一用户语句高度相关，语句级校准高估证据量。缓解：用户级聚类共形、报告 `n_eff`、按用户留出验证。
3. **分层群体覆盖缺口**：总体覆盖达标但少数口音/年龄层失效。缓解：分层共形、最差层报告、专项采样与阈值。
4. **澄清疲劳导致用户乱点确认**：`B_ask` 过高或菜单过长会让用户盲目确认，确认退化为噪声。缓解：限制澄清次数、菜单排序、确认也需要接地证书。
5. **过度信任**：流畅语音与高成功率让用户误以为系统"什么都懂"。缓解：主动披露证书边界、校准反馈、定期"我不知道"演练。
6. **强制猜（为减少追问）**：以满意度为目标会诱导在多候选时猜一个，直接把风险推给假接受。缓解：代价序 `c_fa≫c_fb≫c_ask`、预注册以不安全执行为主指标。
7. **用户分布漂移**：新口音、新环境、群体变化使 `U_u` 与 `Δ_shift` 同时变大。缓解：VSC 漂移检测、确认模式、在线扩样与重校准。
8. **被胁迫/对抗用户**：用户可能故意下达越界命令或快速确认。缓解：语音不能扩权、危险动作二次确认、物理急停独立于语音层。
9. **离板 ASR 延迟破坏 RTIC**：网络往返未计入 `B_time` 会使截止期证书失效。缓解：端侧唤醒+预取、把网络延迟纳入 WCET、超时回退。
10. **用户测试污染与过拟合**：测试集反复用于调参会使迁移界失效。缓解：留出用户、预注册、测试账本只收紧、盲法评分。

## 8. 本轮最大风险

**一句话**：用户级共形保证只对"与校准用户同分布的新用户"成立；一旦部署用户进入新的口音/环境/胁迫场景，VGC 的接地集与 UCC 的覆盖率会同时失效，而 HLR 为压低澄清负担会优先选择高置信单一解释——最终在"每句话都被正确转写、每个用户都在覆盖阈值内、每次执行都在证书集内"的表象下，执行了一个证书允许、用户测试背书、却从未被用户要求的动作，即**合规的、被用户背书的、却绝对违背意图的决定**。
