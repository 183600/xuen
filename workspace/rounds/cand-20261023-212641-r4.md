## 0. 本轮结论

2026-10-23 这轮重新核实了六件事，结论比上一轮更“窄”，也更可执行：

1. **提交接口已经是 v2，而且测试时没有深度/相机标定。** GitHub `unitreerobotics/unibot_submission` 的 v2 commit（2026-08-21）新增了 `obs_delta_indices`（按 key 选观测 + 时序叠帧）、评测端 `image_resize`、以及新的图像序列化。测试观测只有 4 路 RGB（左右高位 + 左右腕）、双臂关节 7+7、base 系 EE pose 6+6、gripper 1+1、`lower_body[15]`、`language`。**没有 depth、没有 camera intrinsics/extrinsics、没有 `state_torso/state_d435/waist_state_joint`**；waist 只藏在 `lower_body[15]` 里。
2. **上轮 SPA-VLA 的“3D part centroid”在测试接口上不成立。** 数据集里确实有头部双目、`state_torso`、`state_d435`、`waist_state_joint` 和标定，但测试端不发这些。上轮的 PoseGraph（head/neck 节点）与“头部双目反投影 3D 部件点”必须降级或删除；否则训练/部署输入不一致。
3. **EE pose 是测试接口的一等公民，而且可以当传感器用。** 数据集原生带 `observation.state.*_ee_pose_gripper_base` 与 `action.*_ee_pose_gripper_base`；官方 UnifoLM-VLA 也用 `G1_EE_6D`（`ACTION_DIM=23`）。v2 的 `obs_delta_indices` 可以免费取回最近若干帧的 EE pose，因此可以在部署时计算 **“指令位姿 vs 实测位姿”的跟踪残差**，作为无传感器的接触/阻塞/扰动代理信号。
4. **`pivot[7]` 不是可以随便填零的。** 数据集 README 明确：`pivot = [vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]`。示例 policy 返回全零只是占位；真实执行时 `height=0` 可能不是安全姿态。必须预测/保持安全 pivot，并在本地评测桩/真机上验证；这是新增的合规风险项。
5. **榜单仍是占位，不能拿分数当证据。** `leaderboard.html` 显示“即将发布”；`runs.html` 是 256/256 占位记录；`details.html` 的 32 个任务视频全部写着“测试视频占位，后续可替换为真实视频文件”。8 行模型名/分数（MolmoAct 29.7% 等）是随机生成，不是真实排名。用户简报的“榜首 <30%”只能当难度直觉。
6. **许可证是硬约束。** `UnifoLM-VLA-Base` 的 HF model card 是 **CC BY-NC-SA 4.0**（非商用 + 相同方式共享），GitHub LICENSE 404；`UnifoLM-WLA-1.0-Base` 是 Apache-2.0；`GigaBrain-0.7-3.5B-Base` 在 2026-10-23 的 HF 页面是 gated/401，许可证未核实（此前摘要称 Apache-2.0，不能默认依赖）；挑战数据集是 Apache-2.0。若规则/后续商业化不允许 NC，官方 VLA 基线不能作为默认底座；优先 Apache-2.0 底座，或在提交 manifest 中明确披露并承担风险。

因此本轮的主判断是：

> **上一轮把边际收益押在“部件分割”上，但测试接口把 3D 部件感知的输入抽掉了；真正没被利用的是“末端位姿的时间序列 + 动作 chunk 的闭环”。** 本轮的创新点从“感知中心”转到“控制中心”：把末端位姿从**动作表示**升级为**传感器**，把“接触最后几毫米、底座/架子被挪、子目标被撤销”变成可检测、可修复的局部闭环。

所以把 RUBICON 3.0 升级为 **RUBICON 4.0 / PDL（Pose-Dynamics Loop）**：

- **ERA（End-effector Relative Action）**：预测当前 EE 系下的相对 SE(3) 动作，部署时再乘回当前实测 EE pose。对底座刚性运动天然等变；数据集原生有 EE 标签；官方基线也走 EE 6D。
- **RDO（Residual Dynamics Observer）**：用 `obs_delta_indices` 取回最近 chunk 的 EE pose 轨迹，比较“上一条指令”与“实际到达”，得到 6D 跟踪残差；用一阶滞后 + Kalman/门控递推最小二乘在线估计自由空间增益，残差超阈值即判定接触/阻塞/滑移/扰动。**不依赖力/触觉传感器**。
- **CHOP（Chunk Horizon Optimizer）**：把 `action_chunk_size` 当成控制参数而不是训练超参；用 p99 推理延迟决定 chunk 下界，接触段用“制动型 chunk”（步长递减 + 末尾 hold），在 180s 内减少开环盲区。
- **SMF（Scene-Motion Factorization）**：用头部背景 homography + 部件 mask 的“整体运动 vs 个体运动”分解，区分“底座/架子被挪”与“物体自己动了”；无需深度/标定，直接服务 T08/T11/T21/T25 的官方干扰。
- **PAS（Part-Anchored Servo）**：上轮 SPA-VLA 的 2.5D 降级版——腕部 2D part mask/centroid + affordance + 视觉伺服，只负责接触最后几毫米；不再依赖 3D centroid。
- **RPSM 2.0**：保留上轮的可逆部件状态谓词，新增“撤销检测 + 只修复被破坏子目标”的 repair prompt/状态机；直接打 T14/T16/T17/T19/T27/T10。
- **Compliance Compiler 2.0**：新增 v2 接口门禁、pivot 安全、许可证门禁（NC 风险）、单模型审计、外部数据/模型披露；这是防归零。
- **Task Portfolio 2.0**：保留 Beta-Binomial + 分层 LPL，新增“模块—任务”归因，把调试预算压到 ERA/RDO/SMF/RPSM 最可能抬成功率的短板上。

与上一轮相比：

- **P0 从 SPA-VLA 换成 PDL（ERA+RDO+CHOP）**：因为测试接口没有 depth/标定，3D 部件感知的输入不成立；而 EE pose 历史是现成的、免费的、每个任务都有的。
- **SPA-VLA 降为 P2/P1**：保留 2D part/affordance 头作为 PAS 的感知前端，不再作为主押注；SAM3/PartSAM 只做离线伪标签，不跑在线第二个模型。
- **PoseGraph（head/neck/torso 节点）删除**：测试端没有 `state_torso/state_d435/waist_state_joint`，也没有相机标定；保留会制造 train-test mismatch。
- **Waist/Pivot 从 P2 降到 P3**：默认保持安全姿态；只有在数据明确显示某任务需要且本地验证安全时才小范围动；`pivot` 的 `height` 必须显式预测/保持，不能填零。
- **“再大一点的 VLA”继续不做**：社区 6.3B LoRA 已经覆盖 32 任务；本轮比的是**接口级状态/控制**和**延迟**，不是参数量。

## 1. 本轮新增/修正的事实

### 1.1 接口 v2（2026-08-21）

- 提交仓库：`https://github.com/unitreerobotics/unibot_submission`；v2 commit `edd0a1c98630671db3375f9c2483d7870dbe031a`，提交信息：*“version 2, support observation-based frame-skipping stacking, image scaling at the test end, and modifies the serialization method before image transmission.”*
- 观测：4 路 RGB + 双臂关节 + base 系 EE pose + gripper + `lower_body[15]` + `language`；**没有** `state_torso`、`state_d435`、`waist_state_joint`、depth、camera params。
- 动作：`control_space` 只能 `"joint"` 或 `"ee"`，二者互斥；两种模式都必须返回 `action.left_gripper`、`action.right_gripper`、`action.pivot[7]`、`meta.token`；joint 额外返回 `action.left_arm/right_arm[7]`，ee 额外返回 `action.left_ee_pose_gripper_base/right_ee_pose_gripper_base[6]`。
- `obs_delta_indices`：**key 决定发送哪些观测**；value 是 ≤0 且严格递增的帧偏移列表，最后一个必须是 0；历史不足用第一帧补齐；`observation.language` 必须是 `[0]`。
- `image_resize`：只对已出现在 `obs_delta_indices` 的图像 key 生效，value 为 `[H, W]`；评测端用 `cv2.resize(frame, (W, H))` 缩放后发送。
- `action_chunk_size`：≥1；每个动作数组形状 `(T_a, ...)`；索引 0 先执行；`meta.token` 不带时间维。
- `metadata.token` 与每次 `get_action` 的 `meta.token` 都必须匹配；否则拒收。
- N 台机器人，端口 `8765 … 8765+N−1`，必须恰好 N 个；N 由组委会公布（README 示例 N=3）。多端口可共享一个模型后端，但**每个端口的状态/reset 必须隔离**。
- 评测端记录每步响应时延、波动、动作统计规律；可能和成绩一起展示。**延迟稳定性是成绩可信度的一部分**。
- 控制频率、N 的具体值、外部数据/模型规则、评分公式细节、pivot 执行语义：**未核实**，按假设/风险处理。

### 1.2 数据集（2026-10-23 复核）

- 32 个任务；约 **33,276 episodes / 169.3h**；30fps；4 路 RGB：`head_stereo_left/right`、`wrist_left/right`；Apache-2.0。
- 观测含 `left_arm/right_arm[7]`、`left_gripper/right_gripper[1]`、`lower_body[15]`（腿 12 + waist yaw/roll/pitch 3）、`left/right_ee_pose_gripper_base[6]`、`left/right_ee_pose_gripper_torso[6]`、`state_torso[6]`、`state_d435[6]`、`waist_state_joint[3]`、`recomputed_ee_valid[1]`。
- 动作含 `left/right_arm[7]`、gripper、`lower_body[15]`、`left/right_leg[6]`、`waist_action_joint[3]`、`left/right_ee_pose_gripper_base[6]`、`left/right_ee_pose_gripper_torso[6]`、`action_torso[6]`、`action_d435[6]`、`base_command[4]`、`pivot[7]`、`gripper_controls[4]`。
- **`pivot` 语义（数据集 README）**：`[vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]`。前三个是 base 速度，最后一个是高度；中间三个是 waist/pivot 目标。示例 policy 的全零 pivot **不是安全默认**；`height=0` 可能让机器人下蹲/失稳。需要模型预测或安全保持，并在本地评测桩验证。
- 语言：`meta/tasks.parquet` 每任务 5 条英文复述；适合留一法语言泛化。
- 时长：6.2s（HangCup）–37.6s（ToolboxStorage）；长任务对 chunk/状态记忆更敏感。
- 标定/深度：数据集有头部双目标定与 depth 相关信息，但测试端不提供；**训练时不能依赖**，只能作为离线教师/增广。

### 1.4 相关 2026 工作（摘要/项目页级）

- **FWBC-VLA**（arXiv 2609.03889）：无传感器残差力矩估计器 HSR-Force + force-aware whole-body compensation，把 contact token 注入 VLA action expert；轮腿平台。
- **Contact-UAN**（CoRL 2026 / project page）：proprioceptive history + 残差 world model，用于人形接触感知；说明“用本体历史估计接触”是可行方向。
- **RePO-VLA**（arXiv 2605.09410）：recovery-driven policy optimization；用恢复片段训练。
- **SPR**（arXiv 2603.09292v2）：See/Plan/Rewind，progress-aware failure recovery。
- **VLA-Corrector**（arXiv 2609.06508v1）：stage-aware observable state understanding + prompt-based closed-loop correction。
- **B2FF**（arXiv 2606.09258）：pre-imagined milestone bank + failure recovery。
- **ForceVLA / TaF-VLA / ResTacVLA / TouchWorld**：依赖力/触觉；本赛没有这些输入。
- **无传感器接触力估计**（PMC13604343；ScienceDirect S0967066126003837）与 **disturbance observer survey**（Robotica）：经典但可复用的观测器思路。
- **结论**：“dynamics + recovery”本身不新，甚至很拥挤；本轮的差异化必须是**接口特定的集成**：EE 跟踪残差、无深度/无标定、官方 undo 协议、单 checkpoint、延迟约束。

### 1.5 评分与统计（沿用并修正）

- 排名：32 任务总平均成功率 ↓ → 总平均步骤分 ↓ → 提交日期 ↑；成功率优先，步骤分只是 tie-breaker。
- 320 次试验（32×10）；p≈0.3 时 `SE≈2.56pp`，95% CI≈±5pp；1–2pp 的榜单差距基本是噪声。
- 要把“排名更高”的概率做到 ~80%，需要约 **3pp** 真实优势；~90% 需要约 **5pp**。
- 一个任务 +10pp → 总平均 +0.31pp；五个 0% 任务各提到 30% → +4.7pp；五个 70% 任务各提到 80% → +1.6pp。**先消灭 0%，再攻短板，不要在强任务上抠 1–2pp。**
- 任务间存在相关性，独立 Bernoulli 的 SE 偏乐观；本地比较用按任务分层的 paired bootstrap，报告 `P(ΔS>0)` 而不是只看均值。

## 2. 三条灵感词的落点

### 2.1 末端位姿 → ERA + RDO

- **ERA**：设当前实测 EE pose 为 `T_t=(R_t,p_t)`，数据集绝对动作为 `A_t`，训练目标改为 `Δ_t=T_t^{-1}A_t`；部署时 `A_t=T_t^{obs}Δ_t`。若底座发生未知刚性变换 `G`，`T_t` 与 `A_t` 同时变成 `G T_t`、`G A_t`，`Δ_t` 不变——**相对动作对底座运动等变**。这正是官方“移动底座/架子”干扰最需要的性质。
- **RDO**：上一条 chunk 的指令 `{T_{t-k}^{cmd}}` 与 `obs_delta_indices` 取回的实测 `{T_{t-k}^{obs}}` 逐帧比较：
  `e_{t-k}=log((T_{t-k}^{cmd})^{-1}T_{t-k}^{obs}) ∈ se(3)`。
  自由空间用一阶滞后/门控 RLS 估计名义跟踪增益；接触/阻塞/滑移时残差出现结构化偏移。Kalman 新息归一化后做阈值/迟滞，避免手调。
- **为什么这是“传感器”**：底层控制器在跟踪目标；跟踪不上，说明环境施加了未建模的约束/力。没有力传感器也能拿到一个 **6D 的接触/扰动代理**；再与腕部视觉的部件状态互补。
- **边界**：如果底层是刚性位置控制且限力很好，残差可能很小；此时用视觉部件状态 + 电流/关节残差（如果接口允许 joint 空间）兜底。不能把它宣传成真实力传感器。

### 2.2 动力学 → 局部跟踪动力学 + 接触制动 + CHOP

- 本轮不做“世界模型/视频扩散”那种全局动力学；做的是 **API 边界上的局部动力学**：指令位姿 → 实测位姿 → 物体状态。
- **接触制动**：当 RDO/视觉预测接触时，chunk 内步长递减，末尾 hold；即使接触发生在 chunk 中间，剩余小步也不会大力顶住。这是对“chunk 开环、无 mid-chunk 反馈”的直接缓解。
- **CHOP**：`action_chunk_size` 由 p99 推理延迟和控制频率决定；训练 chunk 可以 25/50，部署 chunk 可以 8/12。`T_loop≈T_infer+T_exec`；若 `T_infer > k/fps`，机器人会在 chunk 间停顿，动作不连续。**模型大小/延迟是比赛的一等设计变量**：3.5B + 8 步可能比 7B + 25 步更 reactive。
- **PAS**：接触最后几毫米用 2.5D 部件 + 视觉伺服，不用 3D centroid；VLA 负责高层，伺服负责低层，二者共享一个 checkpoint/控制循环，不是在线第二个大模型。

### 2.3 抗干扰 → SMF + RPSM 2.0

- **SMF**：头部背景 homography 估计“相机/底座整体运动”；部件 mask 的 warp 后 IoU 判断“部件是否跟着场景一起动”。整体动 → 底座/架子被挪；个体动 → 物体被移动/撤销。无深度/标定也能做，因为桌面近似平面。
- **RPSM 2.0**：8–12 个通用谓词（grasped/in_hand/inserted/on_hook/closed/stacked/sorted/in_box/aligned/poured/unlocked/…）；谓词回退即撤销；只修复被破坏的子目标；用 repair prompt + 状态机，不重跑全程。
- **官方干扰映射**：
  - 撤销：T14 拧回盖子、T16 翻开毛巾、T17 合上笔盒、T19 拉开拉链、T27 拿走第二个碗、T10 拔起插头 → RPSM。
  - 移除/替换：T12 拿走锁、T29 移开外壳、T28 移动耳机 → RPSM + re-scan。
  - 重置：T24 放回传送带起点 → RPSM + 重新分拣。
  - 移动底座/架子：T08/T11/T21/T25 → SMF + ERA。
  - 阻塞/占用：T05/T10/T26 → RDO + PAS 等待/换目标/重试。
  - 普通位移：大多数 `human_1` → ERA + 部件重检测。

| P1 | **undo/base-motion/latency 数据增广** | 中高：降方差 | 低中 | 真机/回放/图像变换 |
| P1 | **Endurance + dual-rate 视觉编码/KV cache** | 中高：p99/吞吐 | 低中 | 部署工程 |
| P2 | **SPA-VLA 2.5D（part queries/mask/affordance）** | 中：PAS 前端 | 中：收益不如控制环 | 离线 SAM3 伪标签 |
| P2 | **pivot/waist 小范围控制** | 中：少数任务 | 中高：安全/未知语义 | 数据 + 本地验证 |
| P3 | **3D part centroid / PoseGraph head-neck** | 低：测试接口不成立 | 高 | depth/标定不可用 |
| P3 | **世界模型/视频扩散/完整仿真 RL** | 中：长期 | 高：算力/时间 | 仿真资产 |

**一句话排序逻辑**：P0 归成三条主线——**PDL（ERA+RDO+CHOP）**是主押注，**SMF+RPSM 2.0** 直接打官方干扰，**Compliance+Portfolio** 是防归零/预算；不是五个并行大工程。P1 是把硬任务的最后几毫米和部署稳定性补齐；P2/P3 是“看起来酷但本轮不该先做”的项。

## 4. 修剪/暂缓

- **删除 3D part centroid 与头部双目反投影**：测试无 depth/标定；训练用、测试不用是致命 mismatch。
- **删除 PoseGraph 的 head/neck/torso 节点**：测试无 `state_torso/state_d435`；只剩 base 系 EE pose 与 `lower_body`，图节点无法对齐。
- **SPA-VLA 从 P0 降到 P2**：保留 2D part/mask/affordance 作为 PAS 前端；SAM3/PartSAM 只离线做教师。
- **不再把“更大 VLA”当卖点**：社区 6.3B LoRA 已覆盖 32 任务；本轮比接口/控制/延迟。
- **Waist/Pivot 默认静态/安全保持**：不为了“用上 pivot”而乱动；`pivot.height` 不能填零；需要真机/评测桩验证。
- **不做运行时 LLM/VLM API**：延迟/网络/规则风险；repair prompt 离线模板化。
- **不做任务特定坐标/轨迹硬编码**：只保留通用谓词/伺服原语；避免泛化差与合规风险。
- **完整仿真 RL/世界模型先不做**：P3；没有资产/时间，且本轮边际收益在闭环接口。
- **外部数据/模型先默认不用**：规则未核实；只用挑战数据 + Apache-2.0 预训练权重，manifest 披露。

## 5. 为什么这版可能赢

- **对准接口**：测试没有 depth/标定，但有 EE pose 历史；ERA/RDO 用的是接口真实提供的东西，不是数据集里的“奢侈品”。
- **对准干扰**：官方 `human_1/human_4` 的一半是撤销/移除/底座移动；SMF + RPSM 直接打这些轴，而不是泛泛的“鲁棒性”。
- **对准延迟**：评测记录每步时延；CHOP + 3.5B/dual-rate 把 p99 压到 chunk 可覆盖的范围，减少“等模型”造成的停顿。
- **对准评分**：成功率优先；Portfolio 先消灭 0%、再攻 3–5 个短板；不刷步骤分。
- **对准合规**：单模型、v2 接口、pivot 安全、NC 许可证、外部数据披露，全部前置成门禁。
- **竞争空位**：大 VLA 拼语义/数据；本轮拼**接口级状态 + 接触/扰动闭环 + 延迟工程**，这是当前论文/开源提交都没认真做的位置。

## A. 结论

本轮把 RUBICON 3.0 升级为 **RUBICON 4.0 / PDL（Pose-Dynamics Loop）**。核心不是“再大一点的 VLA”，而是三层对准 v2 接口的改造：

1. **ERA + RDO + CHOP（PDL）**：用 EE 系相对 SE(3) 动作抵消底座运动；用 `obs_delta_indices` 取回的实测 EE pose 与上一条指令比较，得到无传感器跟踪残差，检测接触/阻塞/滑移/扰动；用 `action_chunk_size` 与制动型 chunk 处理“chunk 开环、无 mid-chunk 反馈”的限制。
2. **SMF + RPSM 2.0**：用头部背景 homography 与部件 mask 的整体/个体运动分解，区分“底座/架子被挪”与“物体被移动”；用可逆部件谓词检测官方 `human_1/human_4` 的撤销/移除/重置，只修复被破坏的子目标。
3. **Compliance Compiler 2.0 + Task Portfolio 2.0**：把 v2 接口、pivot 安全、单模型、许可证（尤其 UnifoLM-VLA 的 CC BY-NC-SA）、外部数据/模型披露变成门禁；用分层 LPL + Beta-Binomial + 模块—任务归因分配调试预算。

**最重要的口径修正**：上一轮把 SPA-VLA 的 3D 部件质心当 P0，但 2026-10-23 复核发现测试端**没有 depth、没有相机标定、没有 `state_torso/state_d435/waist_state_joint`**；3D 部件感知在测试时不可用。相反，**EE pose 是接口一等公民**，且 v2 的时序叠帧让“指令 vs 实测”的残差免费可得。因此本轮把感知中心降级，把控制/状态闭环升级为主押注。

**最重要的工程修正**：`pivot[7]` 不是可随便填零的占位；数据集 README 明确它是 `[vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]`。示例 policy 的全零 pivot 只是 stub，`height=0` 可能不是安全姿态。必须预测/保持安全 pivot，并在本地评测桩/真机验证；这是新增的合规与安全门禁。

**一句话押注**：把末端位姿从“动作表示”升级为“传感器”——用指令位姿与实测位姿的残差做无传感器接触/扰动观测，用相对 SE(3) 动作抵消底座运动，用场景运动分解与可逆谓词把“底座被挪/子目标被撤销”变成可检测、可修复的闭环。

### B.3 metadata 语义

| 字段 | 语义 | 本赛用法 |
|---|---|---|
| `control_space` | `"joint"` / `"ee"` | 本轮选 `"ee"`；joint 作为辅助损失/消融 |
| `obs_delta_indices` | key → 帧偏移列表；key 决定发哪些观测 | 只声明最小子集；EE pose 取 `[-8..0]` 做 RDO |
| `image_resize` | 图像 key → `[H,W]`；评测端缩放 | 头部 240×320、腕部 160×160/128×128，压带宽/延迟 |
| `action_chunk_size` | 每次返回的步数 | 由 p99 推理延迟决定；候选 8/12/25 |
| `token` | 握手 token | 从 `UNIBOT_SUBMISSION_TOKEN` 读 |

`obs_delta_indices` 细节：

- 偏移必须 `≤0`、严格递增，最后一个必须是 `0`；历史不足用第一帧补齐。
- `observation.language` 必须恰为 `[0]`。
- 只发送声明过的 key；**不要声明测试端不存在的 key**（会拒收/拿不到）。
- 可以非连续采样（如 `[-10,-5,-2,0]`），适合低成本取历史。

### B.4 pivot 语义与安全（新增关键风险）

数据集 README 明确：

```text
pivot[7] = [vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]
```

- 前 3 维是 base 速度命令；第 7 维是高度；中间 3 维是 waist/pivot 目标（具体映射需验证）。
- 示例 policy 返回 `np.zeros((T,7))` 只是最小 stub，**不是安全默认**；`height=0` 可能让机器人下蹲/失稳。
- 数据集中 HangCup/PlugCharger 等任务的默认 pivot 约为 `[0,0,0,0,0.15,0,0.74]`；OrganizeTools 的 `pivot_4` 会随 waist 使用变化（约 0.19→0.01），StorePaddle 的 `pivot_4` 可为 0。**不同任务/不同阶段不同，不能硬编码一个全局零向量。**
- 本轮策略：
  1. 动作头预测 `pivot`，训练时用数据集真值；部署时做范围 clamp + 速率限制。
  2. 首帧若模型不确定，使用**安全默认**：`vx=vy=angle_z=0`，`pivot_3..5` 取当前 `lower_body` 的 waist 角（或数据集中位数），`height` 取数据集安全中位数（约 0.74），并在本地评测桩验证。
  3. 在 `Compliance Compiler` 中加 `pivot_safe` 测试：`height` 不越界、速度不越界、相邻 chunk 不跳变。
  4. 把“pivot 执行语义/安全范围”列为**开放问题**，向组委会确认；未确认前不做激进 base/waist 运动。

### B.5 评测端行为与延迟

- 评测端执行整个 chunk，执行完再调用下一次 `get_action`；**chunk 内没有反馈**。
- 评测端记录每步响应时延、波动、动作统计规律；可能和成绩一起展示。
- 控制频率未在 README 写明；数据集是 30fps。本产物按 **30Hz 保守假设**做延迟预算，实际以本地评测桩/真机为准。
- 端口：N 台机器人，`8765 … 8765+N−1`，必须恰好 N 个；N 由组委会公布（README 示例 N=3）。
- 多端口可共享模型后端，但每端口 `reset`/历史必须隔离；并发不能相互阻塞。

### B.6 接口结论

| 结论 | 影响 |
|---|---|
| 无 depth/标定 | 删除 3D part centroid/PoseGraph head-neck；改用 2.5D 腕部 + 相对位姿 |
| 有 EE pose 历史 | RDO 可行；ERA 可行；这是本轮核心 |
| chunk 开环 | 需要短 chunk/制动型 chunk；不能假设 mid-chunk 反应 |
| 延迟被记录 | CHOP/dual-rate/KV cache 是成绩可信度的一部分 |
| pivot 必填且语义复杂 | 新增 pivot 安全门禁；不能填零了事 |
| 只发声明 key | `obs_delta_indices` 是最小观测契约；声明错会直接失败 |

| `action_torso/action_d435` | 测试不执行 | 不作为监督 |
| head_stereo 命名 | 测试是 cam_left_high/right_high | 训练时做 key 映射/视角增广 |
| `recomputed_ee_valid` | 测试不提供 | 训练时过滤无效帧；部署时相信接口 EE |

**结论**：训练管线必须以“测试可见子集”为输入契约，其他字段只能做离线教师/增广/分析；否则离线指标会骗人。

### C.4 EE 数据与 pivot 数据

- **EE pose 有效性**：数据集有 `recomputed_ee_valid`；训练时只保留 `valid=1` 的帧，避免 IK/重算异常污染 ERA/RDO。
- **EE 表示**：`xyz+rpy`；rpy 在 ±π 附近有 wrap。训练用 6D rotation 或连续 rpy（选与上一帧最近的等价角）；部署输出 rpy 时做连续性修正。
- **pivot 分布**：默认 `height≈0.74`；部分任务 `height≈0.736`；`pivot_3..5` 随 waist 使用变化；前 3 维在公开数据中多为 0。训练时做 per-dim 归一化；部署时 clamp 到数据 1%–99% 分位。
- **夹爪**：Dex1 范围 5.5–0（open→close）；不要把 0/1 当成开/合。归一化到 [0,1] 或 [-1,1] 时明确方向。
- **动作频率**：数据 30fps；chunk 25/50 对应 0.83s/1.67s 开环。部署 chunk 8 对应 0.27s；12 对应 0.4s。

| 切分 | 目的 | 注意 |
|---|---|---|

### D.2 排序公式与统计功效

```text
S = (1/32) * Σ_i (1/10) * Σ_j y_ij          # 总平均成功率
Q = (1/32) * Σ_i (1/10) * Σ_j q_ij          # 总平均步骤分
rank: S desc, then Q desc, then submission_date asc
SE(S) ≈ sqrt( (1/32^2) * Σ_i p_i(1-p_i)/10 )
p_i≈0.3 → SE(S) ≈ sqrt(0.3*0.7/320) ≈ 2.56pp
95% CI ≈ ±5.0pp
```

| 真实成功率优势 Δ | P(观测排名更高) |
|---:|---:|
| 0.5pp | 55.5% |
| 1.0pp | 60.8% |
| 1.5pp | 66.0% |
| 2.0pp | 70.8% |
| 2.5pp | 75.3% |
| 3.0pp | 79.3% |
| 4.0pp | 86.1% |
| 5.0pp | 91.2% |

**含义**：1–2pp 的榜单差距基本是噪声；要把“排名更高”的概率做到 ~80% 需要约 3pp，~90% 需要约 5pp。320 次试验无法靠增加 trials 解决，只能靠更大的真实增益 + 降方差。

**边际价值**：

```text
一个任务 +10pp → 总平均 +0.31pp
一个 0% 任务 → 30% → +0.94pp
五个 0% 任务 → 30% → +4.7pp
五个 70% 任务 → 80% → +1.6pp
```

**结论**：先消灭 0%，再在 3–5 个短板上各拿 20–30pp；不要在强任务上抠 1–2pp。任务间相关，独立 Bernoulli 的 SE 偏乐观；本地比较用按任务分层的 paired bootstrap。

### D.3 Task Portfolio 2.0

对任务 `i` 维护 Beta 后验：

```text
p_i ~ Beta(α_i, β_i)
α_i = α0 + k_i
β_i = β0 + (n_i - k_i)
```

- 先验：Easy `Beta(3,3)`（0.5）、Medium `Beta(2,4)`（0.33）、Hard `Beta(1.5,5)`（0.23）；或统一 `Beta(2,2)`。
- 目标 1：最大化 `E[S] = (1/32) Σ E[p_i]`。
- 目标 2：最大化 `P(S > S*)`，用 Monte Carlo 从后验采样。
- 目标 3：降低 `Var(S)`，提高单次评测抽到好成绩的概率。
- 选择下一个调试任务：`score_i = (E[p_i]-current_i)/cost_i` 或 `UCB_i/cost_i`；对 `P(p_i<0.05)>0.5` 的任务加 no-zero 优先级。
- 成本 `cost_i`：历史调试时长、接触密度、任务时长、失败模式数、所需模块数。

**模块—任务归因**（本轮新增）：

| 模块 | 最可能受益任务 | 预期机制 |
|---|---|---|
| ERA | T08/T11/T21/T25 + 多数位移干扰 | 底座/架子运动等变；重定位 |
| RDO | T10/T26/T12/T14/T19 | 接触/阻塞/滑移检测；制动/重试 |
| CHOP | 所有硬任务/长任务 | 降低 chunk 开环盲区；稳定延迟 |
| SMF | T08/T11/T21/T25 | 区分底座 vs 物体运动 |
| PAS | T10/T26/T14/T19/T27 | 最后几毫米插入/对齐/拉链/拧盖 |
| RPSM | T14/T16/T17/T19/T27/T10/T12/T24 | 撤销/移除/重置检测与修复 |
| SPA 2.5D | 未见物品/部件抓取 | 2D part/affordance 前端 |

**预算分配建议**：P0 模块是全局的，先做；P1 只压 6–8 个硬任务；不要在 10 个 Easy 任务上平均用力。

**统计比较**：同一任务内用 paired bootstrap（同初始条件/同 trial 数），跨任务用分层 bootstrap；报告 `P(ΔS>0)`、均值差、95% CI；不要只看一次 32 任务总分。

## F. 核心系统：PDL（Pose-Dynamics Loop）

### F.1 设计原则

1. **只用测试端真实存在的输入**：4 路 RGB、双臂关节、base 系 EE pose、gripper、`lower_body`、language。depth/标定/torso/D435/waist 独立状态一律不作为部署输入。
2. **把“位姿”同时当动作和传感器**：动作头输出 EE 相对位姿；控制器把上一条指令与实测位姿比较，得到跟踪残差。
3. **局部动力学，不是世界模型**：只建模“指令→实测→物体状态”的短时链路；不训练视频扩散/全局物理模型。
4. **确定性模块与学习模块分离**：RDO/SMF/状态机是控制/估计代码；学习头（动作、谓词、可选 residual/part）在同一个 checkpoint；满足单模型规则。
5. **失败可检测、可修复**：接触/阻塞/撤销/底座移动都有对应的观测信号和低风险动作；检测不到就安全停，不幻觉继续。
6. **延迟是一等约束**：chunk 大小、模型大小、视觉编码频率、KV cache 共同决定有效控制率；不能只追求离线 action loss。

### F.2 ERA：End-effector Relative Action

#### F.2.1 公式

设当前实测 EE pose 为：

```text
T_t = (R_t, p_t) ∈ SE(3)          # base 系
```

数据集绝对动作为 `A_t = (R^A_t, p^A_t)`。相对动作：

```text
Δ_t = T_t^{-1} A_t
R_Δ = R_t^T R^A_t
p_Δ = R_t^T (p^A_t - p_t)
```

部署时用当前实测位姿重建绝对目标：

```text
A_t = T_t^{obs} Δ_t
p^A_t = p_t^{obs} + R_t^{obs} p_Δ
R^A_t = R_t^{obs} R_Δ
```

**底座等变性**：若底座发生未知刚性变换 `G`，则 `T_t' = G T_t`、`A_t' = G A_t`：

```text
Δ_t' = (G T_t)^{-1} (G A_t) = T_t^{-1} G^{-1} G A_t = Δ_t
```

所以 `Δ_t` 对底座运动不变。视觉观测也随底座一起移动（相机固定在机器人上），语言不变；策略输出的相对动作不需要知道 `G`。这正是官方“移动底座/架子”干扰最需要的性质。

#### F.2.2 旋转表示

- 训练用 **6D rotation**（旋转矩阵前两列）或连续 rpy；不要直接回归 3 个欧拉角而不处理 wrap。
- 部署输出 rpy：在等价角 `(r+2πk, p+2πk, y+2πk)` 中选离上一帧最近的一组，避免 ±π 跳变。
- 旋转损失：`L_rot = ||R_Δ^{pred} - R_Δ^{gt}||_F^2` 或 geodesic `arccos((tr(R^T R_gt)-1)/2)`；6D 用 Gram-Schmidt 正交化后计算。
- 平移损失：`L_trans = ||p_Δ^{pred} - p_Δ^{gt}||_1`（对异常值更稳）或 Huber。
- 一致性损失：`L_cons = ||T_t Δ_Δ^{pred} - A_abs^{pred}||`，其中 `A_abs` 是辅助绝对头；让相对/绝对两个头互相约束。

#### F.2.3 训练与部署

```text
训练:
  obs = (4 RGB, arm q, EE pose, gripper, lower_body, language)
  Δ_gt = T_ee^{-1} A_ee
  pred = model(obs)
  L = L_trans(Δ_pred, Δ_gt) + λ_r L_rot + λ_c L_cons
      + λ_j L_joint(aux) + λ_g L_grip + λ_p L_pivot

部署:
  T_obs = obs["...ee_pose_gripper_base"]        # 当前
  Δ_pred = model(obs)                          # chunk × 6
  A_pred = T_obs ⊕ Δ_pred                      # 绝对目标
  A_pred = clamp(A_pred, workspace)
  A_pred = rate_limit(A_pred, prev_cmd)
  return action_chunk(A_pred, gripper, pivot, token)
```

- `control_space="ee"`；joint 头只做辅助损失/消融，不返回 `action.left_arm/right_arm`。
- 夹爪：预测开/合或连续开度；Dex1 范围 5.5–0（open→close），训练时归一化，部署时反归一化并 clamp。
- pivot：预测 7 维；首帧/不确定时用安全默认；做范围 clamp + 速率限制（见 B.4）。
- 工作空间：用数据集 EE pose 的 1%–99% 分位做软 clamp；不要硬编码任务坐标。
- 速率限制：相邻 chunk 的 EE 目标差不超过 `v_max`/`ω_max`；急停/接触时更小。

#### F.2.4 为什么选 EE 而不是 joint

| 维度 | EE | Joint |
|---|---|---|
| 底座运动等变 | **是** | 否（关节目标与底座无关，但世界目标会漂） |
| 视觉伺服/残差 | 直接 | 需 IK/雅可比 |
| 数据标签 | 原生有 | 原生有 |
| 官方基线 | UnifoLM-VLA 用 EE 6D | LingBot LoRA 用 joint delta |
| IK 误差 | 有（底层 IK） | 无 |
| 大范围 reaching | 可能受 IK/限位 | 更稳 |
| 力矩代理 | EE 跟踪残差 | 关节跟踪残差更直接 |

**策略**：主线 EE；joint 作为辅助头/消融。若 E1 显示 joint 在 >50% 任务上明显更好，则改 joint + 关节残差，但保留 EE 辅助头。不要同时返回两套动作（接口不允许）。

### F.3 RDO：Residual Dynamics Observer

#### F.3.1 观测对齐

上一条 chunk 的指令为 `{A_{t-k}, ..., A_{t-1}}`；`obs_delta_indices` 取回实测 `{T_{t-k}^{obs}, ..., T_t^{obs}}`。对齐方式：

```text
e_{t-i} = log( (A_{t-i})^{-1} T_{t-i+1}^{obs} ) ∈ se(3)
```

即“执行完 `A_{t-i}` 后，实际到达与指令的差”。若评测端时序有一步偏移，在本地评测桩校准（比较静止/自由空间段的残差均值），不要假设。

`se(3)` 残差拆成平移 `e_p ∈ R^3` 和旋转 `e_r ∈ R^3`（或旋转角）：

```text
e_p = p_obs - p_cmd
e_r = log(R_cmd^T R_obs)
```

#### F.3.2 名义模型与自由空间校准

自由空间的一阶滞后/偏置模型：

```text
e_t ≈ b + ε_t,   ε_t ~ N(0, Σ)
```

- `b` 是系统性偏置（IK、重力、标定、控制延迟）；用最近 N 个“低残差”帧的**门控递推最小二乘**估计。
- 门控条件：`||e_t|| < τ_free` 且 gripper 状态稳定；接触帧不更新 `b`，避免把接触学进偏置。
- 协方差 `Σ` 用自由空间残差的滑动协方差；接触分数用 Mahalanobis 距离：

```text
s_t = sqrt( e_t^T Σ^{-1} e_t )
contact = s_t > τ_hi for 2 consecutive steps
free    = s_t < τ_lo for 2 consecutive steps
```

- 迟滞避免抖动；`τ_hi/τ_lo` 用自由空间 99%/95% 分位初始化，再按任务校准。
- 若使用 Kalman：状态 `x=[e, ė]`，过程噪声 `Q`，观测 `e`；新息 `ν` 归一化后做分数。实现更平滑，但参数更多；先用门控 RLS + 迟滞，够用再上 Kalman。

#### F.3.3 接触/扰动分类

设指令方向 `d_cmd = log(T_t^{-1} A_t)`，残差方向 `d_e = e_t/||e_t||`：

| 条件 | 解释 | 动作 |
|---|---|---|
| `cos(d_e,d_cmd)>0.7`，gripper open | 撞到/被挡住 | 减速/停下，PAS 重对齐，或换方向 |
| `cos(d_e,d_cmd)>0.7`，gripper closed | 物体卡住/太重 | 小步拉/推，检查夹持，必要时重抓 |
| `cos(d_e,d_cmd)<-0.3` | 被外力推/回弹 | 减小步长，保持，SMF 检查底座/物体 |
| 横向/旋转分量大 | 对不准 | PAS 视觉伺服，旋转对齐 |
| `||e||` 小但物体滑 | EE 跟踪好、物体动 | 腕部视觉/part 状态检测 slip |
| 突然大残差 + 背景动 | 底座/架子被挪 | SMF 重定位，ERA 继续 |

#### F.3.4 动作策略

```text
if contact and not slip:
    scale = 0.3..0.6
    chunk = brake_profile(pred, scale)
    if blocked_count >= 2:
        switch to PAS align/search
elif free:
    chunk = pred
elif base_moved:
    chunk = SMF_warp(pred, H)
else:
    chunk = brake_profile(pred, 0.5)   # 不确定时保守
```

- **制动型 chunk**：`A_i = T_{i-1} ⊕ exp(s_i * log(T_{i-1}^{-1} A_i^{pred}))`，`s_i` 从 1 递减到 `s_min`，最后一步 hold。接触发生在 chunk 中间时，剩余步长很小，不会大力顶住。
- **重试**：同一目标连续 2 次高残差 → 后退 5–10mm，重新对齐；不要原地死顶。
- **安全停**：残差持续超标 + 视觉无进展 + 时间将尽 → 停，保留步骤分，避免损坏。

#### F.3.5 学习式 residual/contact 头（可选）

- 输入：VLA 的视觉/状态 token + 最近 k 帧 EE pose 差；输出：`e_t` 的预测/接触概率。
- 训练：自由空间帧标签 0；接触帧标签 1（用残差阈值 + 视觉人工抽检）；预测残差用 L2。
- 用途：当确定性 RDO 的阈值难调时，学习头给一个先验；但最终决策仍可用门控 RLS/迟滞，便于解释。
- 风险：标签噪声、过拟合；必须在一个 checkpoint 内，不引入第二个模型。

#### F.3.6 可观测性边界

- 若底层位置控制器非常硬且限力完美，EE 残差可能在接触时仍接近 0；此时 RDO 失效，必须靠视觉部件状态/PAS。
- 若底座被移动，`T_cmd` 与 `T_obs` 都在 base 系，残差仍反映“相对 base 的跟踪”；底座运动本身由 SMF 检测，不要混为一谈。
- 若相机/EE 标定有偏，自由空间残差会有偏置；门控 RLS 可以吸收常值偏置，但不能吸收随姿态变化的偏置；训练时用 `recomputed_ee_valid` 过滤。
- 不宣称“力估计”；只宣称“接触/阻塞/滑移的代理信号”。

### F.4 CHOP：Chunk Horizon Optimizer

#### F.4.1 延迟模型

设控制频率 `f`（未核实，按 30Hz 假设），chunk 大小 `k`，推理时间 `T_infer`：

```text
T_exec = k / f
T_loop ≈ max(T_infer, T_exec) + T_overhead
effective_rate = k / T_loop
```

要保持 `effective_rate ≥ f_target`：

```text
k ≥ ceil(T_infer * f_target) + margin
```

例：`T_infer=150ms, f=30` → `k≥5`，选 8；`T_infer=350ms` → `k≥11`，选 12；`T_infer=700ms` → `k≥21`，选 25。

#### F.4.2 训练/部署 chunk 解耦

- 训练 chunk `H=25` 或 `50`（与官方/社区基线对齐）；部署 chunk `k=8/12`，取预测的前 `k` 步。
- 训练时随机丢弃/缩短 chunk，让模型适应不同 `k`；部署时固定 `k`（metadata 固定）。
- 若 `k` 小于训练 `H`，模型仍看到完整未来监督；部署只执行前 `k`，下一次重新预测（receding horizon）。
- 代价：更多调用/更高推理负载；但换来的反应速度/安全性通常值得。

#### F.4.3 制动型 chunk

```text
def brake_profile(A_pred, T0, s_min=0.2):
    A_out = []
    T_prev = T0
    k = len(A_pred)
    for i, A in enumerate(A_pred):
        s = max(s_min, 1.0 - i/(k-1))      # 线性递减
        A_i = T_prev * exp(s * log(T_prev^{-1} A))
        A_out.append(A_i)
        T_prev = A_i
    A_out[-1] = A_out[-2]                  # 末尾 hold
    return A_out
```

- 仅在“预测接触/高残差/不确定”时启用；自由空间用原预测，避免拖慢。
- 也可以在训练时加入 **速度缩放增广**，让模型见过“慢动作”chunk。

#### F.4.4 视觉编码的 dual-rate

- 头部相机随机座/场景变化慢；腕部相机随手臂/接触变化快。
- 头部视觉 token 每 2–4 个 chunk 重算；腕部每个 chunk 重算；语言/头部 KV cache 复用。
- 用 SMF 检测底座/场景运动；一旦变化，立即失效头部缓存。
- 这是降低 `T_infer` 的最大工程杠杆之一；不改变模型结构，只改变调用频率。

#### F.4.5 模型大小 vs 延迟

| 方案 | 语义 | 延迟 | chunk | 风险 |
|---|---|---|---|---|
| 3.5B + 8 步 | 稍弱 | 低 | 8 | 泛化不如 6–7B；需强数据 |
| 6–7B + 12 步 | 强 | 中 | 12 | 可能仍慢；需 FP8/TensorRT |
| 7B + 25 步 | 强 | 高 | 25 | 开环盲区大；接触任务吃亏 |
| 3.5B 蒸馏自 7B | 接近 | 低 | 8 | 蒸馏成本/数据 |

**本轮假设**：在 32 任务、接触密集、延迟被记录的赛制下，**3.5B + 8 步 + 制动**可能比 **7B + 25 步**更优；用 E0/E1 验证，不预设结论。

### F.5 运行时伪代码

```python
class PDLPolicy:
    def __init__(self):
        self.model = load_single_checkpoint()      # 动作 + 谓词 + 可选 heads
        self.prev_cmd = None
        self.rdo = ResidualObserver()
        self.smf = SceneMotionFactorizer()
        self.rpsm = ReversibleStateMachine()
        self.pivot_safe = load_safe_pivot()
        self.k = choose_chunk_size_from_latency()

    def get_action(self, obs):
        # 1. 解析 v2 观测（只含声明的 key）
        T_obs = obs["observation.state.left/right_ee_pose_gripper_base"]
        imgs = obs["observation.images.*"]
        lang = obs["observation.language"]

        # 2. 场景运动分解（头部）
        H, base_moved, obj_moved = self.smf.update(imgs.head)
        if base_moved:
            self.rpsm.on_base_moved(H)

        # 3. 残差/接触（用上一 chunk 指令 + 当前/历史 EE）
        e, contact, slip = self.rdo.update(self.prev_cmd, T_obs)
        self.rpsm.update(contact=contact, slip=slip, base_moved=base_moved)

        # 4. 单模型前向：动作 + 谓词 + 可选 residual/part
        pred = self.model(imgs, T_obs, lang, aux_tokens=(H, contact, slip))

        # 5. 相对动作 -> 绝对目标；制动/限幅
        A = compose(T_obs, pred.delta)
        if contact or slip or base_moved:
            A = brake_profile(A, T_obs, s_min=0.25)
        A = clamp_workspace(A)
        A = rate_limit(A, self.prev_cmd)

        # 6. 谓词回退 -> repair prompt / 子目标
        repair = self.rpsm.repair_prompt()
        if repair:
            pred = self.model(imgs, T_obs, lang + " " + repair)
            A = compose(T_obs, pred.delta)

        # 7. 安全 pivot + token + chunk
        pivot = safe_pivot(pred.pivot, T_obs, self.pivot_safe)
        self.prev_cmd = A
        return build_action(A[:self.k], pred.gripper[:self.k],
                            pivot[:self.k], token)
```

### F.6 失败模式与停止条件

| 失败模式 | 检测 | 处理 | 停止条件 |
|---|---|---|---|
| 自由空间残差噪声大 | 自由段 `s_t` 分布宽 | 增大 `τ`，用滑动协方差 | AUC<0.65 → 关闭 RDO，仅用视觉 |
| 刚性控制器掩盖接触 | 残差小但物体未动 | 腕部视觉/part 状态 | 连续 2 次无进展 → PAS/重试 |
| chunk 太长 | 接触后仍执行旧目标 | 制动/短 chunk | 超时/力过大 → 停 |
| 底座被挪 | SMF 背景 homography 大 | 重定位/ERA | 重定位失败 → 重新扫描 |
| 撤销/移除 | 谓词 true→false | repair prompt/子目标 | 无法恢复 → 安全停 |
| 单模型审计 | 多 checkpoint/多 API | 合并/文档 | 无法合并 → 放弃该模块 |

## G. PAS：Part-Anchored Servo（2.5D）

### G.1 动机

上轮 SPA-VLA 假设能拿到 3D 部件质心/法向；测试端没有 depth/标定，这个假设不成立。但腕部 RGB 仍然能看到部件近景，且 32 任务几乎都是部件级交互。PAS 把“部件”降级为 **2D mask/centroid + affordance + 局部尺度**，只负责接触最后几毫米；高层语义/目标选择仍由 VLA 负责。

### G.2 2.5D 部件表示

| 字段 | 来源 | 用途 |
|---|---|---|
| 2D mask `M` | VLA part head / 离线 SAM3 伪标签 / 传统分割 | 部件区域、遮挡判断 |
| centroid `u=(u,v)` | mask 均值/最大内切圆 | 视觉伺服目标 |
| affordance `a` | 语言/任务 + part query | 抓/插/挂/拉/拧/倒 |
| 局部尺度 `s` | mask 面积/已知物体尺寸 | 粗深度/步长 |
| 方向 `d` | PCA/拟合轴 | 插入/拉链/旋转对齐 |
| 置信度 `c` | part head | 低置信度时不用伺服 |

**不做**：3D centroid、法向、点云、相机标定。需要 3D 时用 EE pose + 相对动作，而不是从图像反投影。

### G.3 视觉伺服

图像误差 `e_u = u - u*`；局部图像雅可比 `J = ∂u/∂p`（2×3/2×6）。无深度时 `J` 的平移尺度有歧义；三种解法：

1. **离线拟合局部雅可比**：用数据集里同一任务/部件的 `(u, EE pose)` 对，拟合 `Δu ≈ J Δp`；按部件/视角分桶。简单、可解释。
2. **在线试探**：发一个小 EE 位移，观测 `u` 变化，估计 `J` 的符号/比例；只在小范围用，避免接触。
3. **无标定视觉伺服**：只控制图像误差的**方向/符号**，步长固定小值，靠 RDO/接触反馈停止；牺牲速度换鲁棒。

控制律：

```text
Δp = -λ * pinv(J) * (u - u*)
Δp = clamp(Δp, δ_max)
if ||u-u*|| < ε: hold / 切换到力/残差微调
if residual high: back off, re-align
```

- 插入：先对齐部件轴 `d` 与孔轴，再沿 `d` 小步推进；每次推进后检查 RDO 残差/视觉插入深度。
- 拉链/拧盖：用 `d`/mask 主轴估计旋转角；小角度步进，残差高则回退。
- 挂杯/放盘：对齐 handle/rim 与 hook/rack 的 2D 关系；z 由 EE 相对动作/残差控制。
- 倒药/倒水：用瓶口/杯口 mask 与目标容器 mask 的相对位置；角度由 VLA 预测，PAS 只对齐。

### G.4 通用接触原语

| 原语 | 输入 | 动作 | 停止条件 |
|---|---|---|---|
| `align` | 2D 目标 `u*`, 轴 `d` | 小步平移/旋转 | 图像误差 < ε |
| `insert` | 插入轴、孔 mask | 沿轴小步推进 | 残差上升/深度到位 |
| `pull` | 拉链/插头 mask | 沿轴拉，力代理上升即停 | 位移到位/滑脱 |
| `hang` | handle/hook mask | 对齐后下降，残差检测挂住 | 谓词 on_hook |
| `zip` | slider/pull mask | 沿齿方向拉 | 谓词 closed |
| `pour` | 瓶口/容器 mask | 对准后旋转 | 谓词 poured/时间 |
| `rotate` | 盖/锁 mask | 小角度拧 | 谓词 tight/unlocked |

原语由 VLA 的 affordance/language 选择，**不看任务 ID**；同一原语跨任务复用。

### G.5 训练/实现

- Part head：VLA 内部 8–16 个 part queries，输出 mask/centroid/affordance/confidence；用 SAM3/PartSAM 离线伪标签 + 人工抽检。
- 只对关键帧/腕部视图标注，降低成本；2D mask 比 3D 便宜。
- 伺服增益/步长用本地评测桩调；不进入 checkpoint（确定性控制）。
- 与 RDO 互补：RDO 检测“推不动”，PAS 负责“对准”；RDO 检测“滑”，PAS 重对齐/重抓。
- 单模型：part head 在 checkpoint 内；伺服是控制代码，不是第二个学习模型。

### G.6 限制

- 腕部视野可能看不到目标（遮挡/太近）；用另一腕/头部补，或先退开再对齐。
- 无深度导致尺度歧义；用离线雅可比/小步试探/固定步长。
- 2D mask 抖动；用置信度/时序平滑/迟滞。
- 透明/反光物体（试管、瓶子）分割难；用边缘/高光/多视角。
- 伺服可能振荡；加强阻尼/步长限制/停止条件。

## H. SMF：Scene-Motion Factorization

### H.1 问题

官方干扰包括 T08 抓书后挪架子、T11 抓电池前动底座、T21 把架子向左移、T25 放第一个后挪底座。底座/架子一动，头部相机视角整体变化，上轮的部件记忆/外参会失效；但测试端没有标定，不能重算外参。SMF 用图像运动分解来区分“场景整体动”与“物体自己动”。

### H.2 背景 homography

对相邻两帧头部图像 `I_{t-1}, I_t`：

1. 降采样到 240×320；提取 ORB/SIFT/Shi-Tomasi 特征；光流/LK 跟踪。
2. RANSAC 拟合 homography `H_t`（至少 4 对点，DLT）。
3. 内点率 `ρ_bg`；内点重投影误差 `ε_bg`。
4. 若 `ρ_bg > τ_bg` 且 `ε_bg < τ_e`，认为背景是平面/准平面，`H_t` 是相机运动。

桌面/架子/传送带大致平面，homography 是合理近似；不需要相机内参。

### H.3 整体 vs 个体运动

对每个部件 mask `M_{t-1}`：

```text
M_warp = warp(M_{t-1}, H_t)
IoU = |M_warp ∩ M_t| / |M_warp ∪ M_t|
```

| 背景 | 部件 IoU | 解释 | 动作 |
|---|---|---|---|
| 动（`H_t` 非单位） | 高 | 部件跟着场景动 → 底座/架子被挪 | 用 `H_t` 更新部件位置/目标；不重置进度 |
| 静（`H_t≈I`） | 低 | 部件自己动 → 物体被移动/撤销 | 更新物体状态；RPSM 检测 |
| 动 | 低 | 两者都动/遮挡 | 标记不确定；重新扫描/等待 |
| 静 | 高 | 无运动 | 正常 |

`H_t` 是 2D 投影变换；对部件 centroid 直接 warp 即可；对 EE 目标，用 `H_t` 调整图像目标，再通过 ERA/PAS 转成相对动作。没有 3D 深度也能做 2D 重定位。

### H.4 部件一致性 fallback

背景纹理少/反光时，homography 可能失败。用部件自身特征：

- 对每个可见部件 mask 内的特征，计算中位 2D 位移 `d_i`。
- 若所有 `d_i` 接近（`||d_i - median|| < τ`），推断整体运动（底座/架子）。
- 若某个 `d_i` 明显不同，推断该物体运动。
- 若部件太少/全遮挡，标记不确定，等待/退开。

### H.5 机械臂遮挡

- 头部视野里机械臂也在动，可能主导特征。用**顺序 RANSAC**：先找最大平面（背景），再找第二平面（桌面/架子），把机械臂当外点；或用品部件 mask/腕部视图排除。
- 若机械臂覆盖大部分背景，SMF 置信度低；此时不要强行重定位，用 RPSM 的“重新扫描”/等待。
- 可选的离线机械臂分割（SAM3）只用于特征掩码，不参与在线策略；不违反单模型（是预处理）。

### H.6 与策略的接口

- 输出：`H_t`、`base_moved`、`obj_moved`、每个部件的 `motion_label`、置信度。
- 策略：把 `base_moved/obj_moved` 作为辅助 token（离散/连续）输入 VLA；或用 `H_t` warp 上一帧的 part mask/目标，作为额外视觉通道（内部特征，不改变接口）。
- 更新：`base_moved` 时，RPSM 不重置谓词，只更新空间目标；`obj_moved` 时，按谓词回退/修复。
- 缓存：`base_moved` 时立即失效头部视觉 KV cache。

### H.7 实验与限制

- 实验：T08/T11/T21/T25 脚本化移动 5/10/15cm；测 part centroid 重定位误差、成功率、误报率；对比 no-SMF。
- 限制：平面假设；纹理少/反光；机械臂遮挡；动态物体（传送带）本身在动，homography 可能把它当背景；需要把传送带区域 mask 掉或单独建模。
- 结论：SMF 不是“重定位 SLAM”，而是**低成本的场景运动解释器**；够用来决定“该更新目标还是该修复状态”。

## I. RPSM 2.0：Reversible Part-State Memory

### I.1 谓词集合（8–12 个通用）

| 谓词 | 含义 | 典型任务 |
|---|---|---|
| `grasped` | 夹爪夹住目标部件 | 所有抓取 |
| `in_hand` | 物体稳定在手中 | 搬运 |
| `inserted` | 插头/试管/针头插入 | T10/T26/T13/T32 |
| `on_hook` | 杯/工具挂上 | T01/T23 |
| `closed` | 拉链/盒/盖闭合 | T17/T19/T14 |
| `stacked` | 物体叠放 | T20/T25/T27 |
| `sorted` | 物体进入目标容器/位置 | T04/T24/T02 |
| `in_box` | 物体在盒/包内 | T03/T18/T28/T29 |
| `aligned` | 相框/盘子/工具对齐 | T07/T15/T21 |
| `poured` | 药品/水倒出 | T14/T32 |
| `unlocked` | 锁打开 | T12 |
| `tight` | 盖子拧紧 | T14 |

谓词是**部件级/关系级**，不是任务 ID；同一谓词跨任务复用。

### I.2 状态机

```text
belief[p] ∈ [0,1]; state[p] ∈ {unknown, true, false}
每帧:
  belief[p] = EMA(pred_head(p), α)
  if belief[p] > τ_hi and prev != true: state=true
  if belief[p] < τ_lo and prev == true: state=false; undo_event(p)
  if base_moved: 不重置 state，只更新空间目标
  if obj_moved and p空间相关: 标记可能回退
```

- 迟滞/EMA 防抖；谓词头输出多标签 BCE。
- `undo_event` 记录时间/部件/置信度；repair 选择器按“最低成本恢复”排序。
- 若 `state` 不确定（`τ_lo < belief < τ_hi`），不触发 repair；继续观察/主动扫描。

### I.3 撤销检测

三类证据：

1. **谓词回退**：`true→false`（如 `zipped`→false、`stacked`→false）。
2. **空间回退**：部件/物体 centroid 回到之前的位置（SMF/part track）。
3. **视觉回退**：腕部图像中部件状态（盖子松开、拉链打开、毛巾展开）与记忆不符。

融合：`undo_score = w1*Δbelief + w2*Δpose + w3*visual`；超过阈值 → undo。对官方 `human_1/human_4`，用脚本化干预校准阈值。

### I.4 修复

```text
repair(p):
  if p == zipped and not closed: prompt="close the zipper again"
  if p == tight and not tight:   prompt="tighten the cap again"
  if p == stacked and not stacked: prompt="restack the bowl"
  if p == inserted and not inserted: prompt="reinsert the plug"
  if p == in_box and not in_box: prompt="put the object back"
  if p == sorted and not sorted: prompt="resort the object"
  ...
```

- repair prompt 是**通用模板**，追加到原语言；不换任务、不喂任务 ID。
- 只重做被破坏的子目标；不 reset 整个 episode；180s 预算下优先最低成本。
- 若 repair 两次失败 → 回退到更早的安全子目标/重新扫描；仍失败 → 安全停。
- 与 RDO/PAS 协同：repair 后若接触残差高，先 PAS 对齐；若底座动了，先 SMF 重定位。

### I.5 训练标签

| 来源 | 标签 | 成本 |
|---|---|---|
| 成功 episode + `score_steps` | 检查点前后的谓词正样本 | 低 |
| 人工抽检 | 关键帧谓词/部件状态 | 中 |
| 反向播放 | `true→false` 负样本/undo | 低 |
| 脚本化 undo | 官方 human 备注的干预 | 中高（需真机/仿真） |
| 合成遮挡/移除 | 物体消失/位移 | 低（图像增广） |
| 失败 episode | 失败前谓词/状态 | 低 |

- 标签不平衡：对稀有谓词过采样/加权；用 focal loss。
- 时序一致性：`L_temporal = ||belief_t - belief_{t-1}||` 在无事件时惩罚跳变。
- 反向播放的物理可能不真实，但足以教“状态回退”的视觉模式；不要把它当真实动力学。

|---|---|---|---|
| T14 | 拧开盖子后拧回 | `tight` | 再拧紧 |
| T16 | 叠好的毛巾翻开 | `folded`（可加） | 再叠 |

### I.7 限制

- 谓词标签是最大成本；没有标签时先用规则/视觉启发式，逐步补。
- 官方 human 干预有随机性；本地脚本无法完全复现；用多种强度/时序增广。
- 单模型规则：谓词头在 checkpoint 内；状态机是确定性代码，需在 Compliance 中说明。
- 过拟合官方备注：谓词/repair 模板保持通用；不要写“T14 专用”。

### J.2 模型与动作头

- Backbone：3.5B（延迟优先）或 6–7B（语义优先）；LoRA/partial fine-tune；冻结视觉编码器的大部分层。
- Action head：flow matching（或 diffusion/FAST）；输出 chunk `H=25/50`；EE 相对 6D + gripper + pivot。
- 辅助头：绝对 EE、joint、谓词、可选 residual/contact、可选 2D part。
- 单 checkpoint：所有学习头共享 backbone；部署一次前向；不加载第二个模型。
- 归一化：per-dim mean/std；EE 平移/旋转分别归一化；pivot 按数据分位 clamp；gripper 方向明确。
- 时间集成：可选 ACT/扩散的 temporal ensembling；但会引入延迟，先用简单 chunk。

### J.3 损失

```text
L = λ_t L_trans(Δ_pred, Δ_gt)
  + λ_r L_rot(R_pred, R_gt)
  + λ_c L_cons(T_t Δ_pred, A_abs_pred)
  + λ_j L_joint(q_pred, q_gt)          # 辅助
  + λ_g L_grip(g_pred, g_gt)
  + λ_p L_pivot(p_pred, p_gt)
  + λ_pred L_pred(pred_head, labels)   # 谓词
  + λ_res L_res(e_pred, e_gt)          # 可选
  + λ_reg ||θ||^2
```

- `L_trans`：L1/Huber；`L_rot`：geodesic/6D；`L_cons`：L2。
- 谓词：BCE/focal；时序平滑。
- 残差头：自由空间 L2 + 接触对比/BCE；标签噪声大时降权。
- 不要让辅助损失压过动作主损失；用 uncertainty weighting 或固定小权重。

### J.4 数据管线

1. 读取 LeRobot v3 parquet/video；按 episode 解码 4 路 RGB。
2. 过滤 `recomputed_ee_valid=1`；缺失/异常 EE 帧丢弃或插值。
3. 构造 EE 相对动作 `Δ=T_ee^{-1} A_ee`；绝对动作用于辅助头。
4. 构造 pivot 目标；按数据分位 clamp；记录每任务分布。
5. 语言：5 条复述；训练随机选一条；留一法验证。
6. 采样：任务平衡 + 帧平衡；长任务不要过度采样；硬任务适度过采样。
7. 图像：训练随机 resize/crop/color jitter（轻度）；部署固定 resize；不要用测试端没有的 depth。
8. 验证：按 episode/任务/语言/未见物品分层；记录每类指标。

### J.5 增广

| 增广 | 目的 | 方法 | 风险 |
|---|---|---|---|
| EE 相对动作 | 底座等变 | 天然；无需图像变换 | 物体动时标签仍对 |
| 图像 homography/affine | 底座/视角变化 | 随机 2D 变换 + 调整 2D 目标 | 3D 一致性不完美 |
| 底座移动 | SMF/ERA | 本地移动底座/架子；或图像 warp | 需真机/仿真 |
| 撤销 | RPSM | 反向播放/脚本化 human | 物理不真实 |

| 动作噪声/延迟 | RDO/鲁棒 | 加噪声、延迟 chunk、drop | 过度增广降低精度 |
| chunk dropout | CHOP | 随机截断 chunk | 训练/部署一致 |
| 语言复述 | 语言泛化 | 5 条 + 模板 | 官方语言可能不同 |

### J.6 训练资源（估算）

- 3.5B LoRA/partial：4×A100/H100 40–80GB，1–2 周（取决于数据解码/分辨率）；先用小分辨率/子集跑通。
- 6–7B：8×A100/H100 或更多；LoRA + gradient checkpointing；2–3 周。
- 数据解码是瓶颈：预先解码/缓存 4 路 RGB 到低分辨率；用 DALI/ffmpeg/LeRobot dataloader。
- 评估：本地评测桩 32 任务 × 10 trials 很贵；先用 5–8 任务 × 5 trials 做迭代，再用分层 LPL 做全量。

### J.7 离线/闭环评估

| 指标 | 用途 | 目标 |
|---|---|---|
| EE 平移/旋转误差 | ERA 拟合 | 低于基线；按任务分层 |
| 接触检测 AUC/延迟 | RDO | AUC>0.75；延迟<2 chunk |
| 谓词 F1/回退延迟 | RPSM | F1>0.7；延迟<1s |
| 底座重定位误差 | SMF | <2cm/2°（2D 近似） |
| 闭环成功率 | 最终 | 分层 LPL；paired bootstrap |
| p50/p95/p99 延迟 | CHOP | p99 稳定；无长尾 |
| 4h soak 成功率漂移 | Endurance | <2pp |

## K. 部署、延迟与交互质量

### K.1 服务架构

```text
                ┌──────────────────────────────┐
                │  shared inference backend     │
                │  one checkpoint / one model   │
                │  dynamic batching by deadline │
                └──────────────┬───────────────┘
                               │
        ┌──────────────┬───────┴───────┬──────────────┐
        │ port 8765    │ port 8766     │ ...          │ port 8765+N-1 │
        │ session A    │ session B     │              │ session N     │
        │ state/reset  │ state/reset   │              │ state/reset   │
        └──────────────┴───────────────┴──────────────┘
```

- 每个端口一个轻量 HTTP/WebSocket 端点；每端口独立 `session_id`/episode 状态/RPSM 记忆/prev_cmd。
- 共享后端只保留模型权重；请求携带 `session_id`，状态不串。
- `reset` 清空 prev_cmd/RDO/SMF/RPSM；不重置模型权重。
- 并发：按 deadline 组 batch；某端口慢请求不能阻塞其他端口；超时返回保守 hold/安全动作，而不是崩溃。
- token：握手 `metadata.token` + 每次 `meta.token`；从环境变量读，不写日志。
- `UNIBOT_CONTROL_SPACE` 与 metadata 一致；启动时断言。
- N 未知：按 N=1/2/3/4 做压测；端口数必须恰好 N，不能多开/少开。

### K.2 延迟预算

| 组件 | 目标（3.5B，30Hz 假设） | 手段 |
|---|---|---|
| 图像 resize/传输 | <20ms | 头部 240×320、腕部 128×128/160×160；msgpack/共享内存（若允许） |
| 视觉编码 | <60ms | dual-rate 头部、TensorRT/FP8、冻结/蒸馏 |
| 语言/头部 KV cache | <10ms | 复用；SMF 变化时失效 |
| 动作头 | <30ms | flow matching 少步/蒸馏；批量 |
| 后处理/伺服 | <10ms | NumPy/TorchScript；避免分配 |
| 总计 p50 | <120ms | 目标；p99 <200ms |
| 总计 p99 | <250ms | 告警；>500ms 需降级 |

> 以上是工程目标，不是实测；控制频率未核实，必须用本地评测桩/真机测。

### K.3 带宽与观测契约

- `obs_delta_indices` 只声明模型真正用的 key；不要为了“可能有用”多要 4 路原图。
- `image_resize` 在评测端缩放，省带宽；训练时用相同/随机分辨率。
- 头部视觉不需要每 chunk 都算；腕部需要；用 dual-rate。
- 若网络带宽不足，优先降头部分辨率/帧率，不降腕部（接触信息）。
- 不要声明 `state_torso/state_d435/waist_state_joint` 等测试端不存在的 key。

### K.4 稳定性

- 4h soak：N 端口并发、随机任务、随机延迟；记录成功率漂移、p99 漂移、显存增长、热节流。
- 内存：固定 batch/分辨率；避免 Python 对象泄漏；每 episode 清理缓存；监控 RSS/VRAM。
- 热：GPU 温度/频率；降频时 p99 上升；准备降级策略（更小分辨率/更短 chunk）。
- 崩溃恢复：进程守护/健康检查；重启后 warmup；端口重连。
- watchdog：单次 `get_action` 超时 → 返回 hold/安全动作；连续超时 → 标记失败，不拖垮其他端口。
- 日志：只记录指标，不记录 token/密钥；错误可复现。

### K.5 动作规律性

- 平滑：EE 目标 rate limit；pivot 速率限制；gripper 不要高频抖动。
- 无离群：clamp 工作空间/关节范围；NaN/Inf 检查；异常时 hold。
- 一致性：相邻 chunk 的目标差有界；制动型 chunk 末尾 hold。
- 不要返回全零/常量动作（除了真正的 hold）；评测端会看动作统计规律。
- 时间维度/数据类型严格匹配：`(T_a, dim)`、float32；`meta.token` 不带时间维。

### K.6 实验 E0（接口/延迟）

- 目的：在目标 GPU 上测 p50/p95/p99，选 chunk/分辨率/模型。
- 变量：模型 3.5B/7B；chunk 1/4/8/12/25；分辨率 480×640/240×320/160×160；4 路 vs 2 路腕部。
- 指标：单次 `get_action` 延迟、端到端 loop、有效控制率、显存、温度。
- 通过：3.5B + 8 步 p99 <250ms；7B + 12 步 p99 <400ms；否则降级。
- 停止：p99 >500ms 且无法通过 TensorRT/FP8/分辨率解决 → 换更小模型/蒸馏。

### K.7 部署风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| N 未知 | 端口数不对直接失败 | 按 N=1/2/3/4 压测；启动读环境/配置；manifest 写明 |
| 控制频率未知 | chunk 预算错 | 本地评测桩测；保守 30Hz；可配置 |
| 网络抖动 | p99 爆 | 重试/超时/hold；batch deadline |
| 热节流 | 长时成功率下降 | 监控/降频/降分辨率 |
| 多端口状态串 | 结果错乱 | session 隔离/reset 测试 |
| token 泄漏 | 安全/合规 | 环境变量；日志脱敏 |
| pivot 不安全 | 摔倒/损坏 | 安全默认/clamp/速率限制/真机验证 |

### L.2 单模型审计

- 一个 checkpoint 文件；动作头、谓词头、part head、residual head 共享 backbone。
- 不允许“按任务选择不同 checkpoint”“按语言调用不同模型”“在线调用第二个 VLM/分割 API”。
- RDO/SMF/RPSM 是**确定性控制/估计代码**：输入 obs/上一指令，输出残差/变换/状态；不含任务特定学习参数；在 manifest 中列明。
- 如果组委会把任何辅助模型都算“多模型”，则把可学习部分合并进 checkpoint；确定性数学模块保留为控制代码，并提前书面确认。
- 运行时日志记录：模型 hash、checkpoint 数、外部调用数（应为 0）、任务 ID 是否进入模型（应为否）。

### L.4 外部数据/模型门禁

- 规则 2.3–5.2 未读；外部数据/模型是否允许**未核实**。
- 默认保守：只用挑战数据集 + Apache-2.0 预训练权重 + 自建代码；不使用外部机器人数据/闭源 API。

### L.5 无任务硬编码

- 不把任务 ID、任务名到坐标/轨迹的映射写进代码。

- 代码审计：搜索 `if task ==`、坐标常量、任务 slug；红队用未见任务/改写语言测试。

### L.6 人机安全

- 人为干扰就在工作区；任何突然的 base/waist 运动都可能撞人。
- 默认 `vx=vy=angle_z=0`；pivot 只做小范围/低速；不主动走向人。
- 工作空间软/硬限位；速度/加速度限制；接触残差高时减速/停。
- watchdog：超时/异常 → hold/安全停；不继续执行旧 chunk。
- 急停/暂停：如果接口/平台提供，必须响应；本地评测桩模拟。
- 不做“绕过安全限制”的优化；安全是成绩可信度的一部分。

### M.2 E1 细节（EE vs joint / relative vs absolute）

- 数据：同任务/同 episode 留出；构造 4 种动作标签：EE absolute、EE relative、joint absolute、joint delta。
- 离线：平移/旋转误差、chunk 平滑度、接触段误差。
- 闭环：5–8 任务（含 T08/T10/T11/T21/T25/T26），每任务 5–10 trials；底座移动子集。
- 统计：paired bootstrap；报告 `P(ΔS>0)`。
- 通过：EE relative 在底座移动子集 +2pp 以上，整体不下降；否则保留绝对/ joint。
- 停止：EE relative 在 >50% 任务明显下降 → 只做辅助头。

### M.3 E2 细节（RDO）

- 采集：T10/T26/T12/T14/T19，每任务 20–30 episodes；记录指令 chunk、实测 EE、gripper、腕部视频。
- 标签：接触 onset 用视频人工抽检 + gripper 闭合 + 物体运动；自由空间段为负。
- 指标：AUC、接触延迟（步/chunk）、误报率、不同阈值敏感性。
- 通过：AUC>0.75；延迟≤2 chunk；自由空间误报<5%。
- 停止：AUC<0.65 → 关闭 RDO，仅用视觉/PAS；保留离线分析。

### M.4 E3 细节（PAS）

- 任务：T10/T26（插头/网口）、T14（拧盖）、T19（拉链）；可选 T27。
- 对照：VLA-only；VLA+RDO 制动；VLA+PAS；VLA+RDO+PAS。
- 指标：成功率、完成时间、接触尝试次数、残差峰值、超时率。
- 通过：PAS 在至少 2 个任务 +10pp 或时间 -20%；无安全事件。
- 停止：伺服振荡/频繁误对齐 → 降低增益/只做 RDO 制动。

### M.5 E4 细节（SMF）

- 任务：T08/T11/T21/T25；脚本移动底座/架子 5/10/15cm，随机方向/时刻。
- 指标：part centroid 重定位误差、成功率、误报（把物体动当底座动）、延迟。
- 通过：至少 2 个任务 +10pp；误报<10%。
- 停止：平面/纹理失败严重 → 只用部件一致性 fallback；或改为重新扫描。

### M.6 E5 细节（RPSM）

- 任务：T14/T16/T17/T19/T27/T10；按官方 `human_1/human_4` 脚本化 undo；随机时刻/强度。
- 指标：undo 检测延迟、repair 成功率、time-to-recover、总成功率、误触发。
- 通过：至少 3 个任务 +10pp；检测延迟<1s；误触发<5%。
- 停止：标签成本过高 → 只用 repair prompt 启发式；不做谓词头。

### M.7 E6 细节（Portfolio/LPL）

- 32 任务 × 10 trials；5 类泛化各 2；本地脚本化。
- 指标：每任务成功率/步骤分、总平均、Beta 后验、模块归因。
- 通过：识别 top5 短板；下一轮预算分配；无 0% 任务（或明确不可达）。
- 统计：分层 paired bootstrap；`P(ΔS>0)`；不要只看一次总分。

### M.8 E7 细节（全量/soak/合规）

- 32 任务 dry run；N 端口并发；4h soak；随机延迟/错误注入。
- 指标：成功率、p99、显存/温度、崩溃/重启、合规 checklist。
- 通过：无违规、无 zero、p99 稳定、可复现。
- 停止：任何单模型/许可证/接口违规 → 先修复再提交。

| 移除物体 | T12/T29/T28 | RPSM + re-scan | 找不到 → 安全停/换目标；不幻觉继续 |

| 人为遮挡 | 任意 | RDO + 视觉 | 残差/遮挡检测 → hold/等待 |

## S. 反证条件与开放问题

### S.1 什么会让我们改变主意

1. **RDO 不可观测**：5 个接触任务 AUC<0.65，或自由空间误报>10% → 关闭 RDO，退回视觉/PAS。
2. **ERA 不优**：相对 EE 在 >50% 任务明显低于绝对/joint → 降为辅助头，主线改 joint/绝对。
3. **SMF 无增益**：4 个底座任务中 <2 个 +10pp，或误报>20% → 改为重新扫描/等待。
4. **RPSM 标签太贵**：2 周内做不出可用谓词头 → 只用 repair prompt 启发式。
5. **3.5B 太弱**：全任务 LPL 比 6–7B 低 >5pp → 换 7B + 12 步；接受较低反应性。
6. **7B 太慢**：p99>500ms 且无法通过 TensorRT/FP8/dual-rate 解决 → 3.5B/蒸馏。
7. **pivot 不安全/语义不明**：无法在本地评测桩验证 → 只输出保守保持，不做 base/waist；向组委会确认。
8. **单模型规则不允许确定性模块**：无法合并/解释 → 删除独立模块，只保留 checkpoint 内头。
9. **NC 许可证不允许**：不用 UnifoLM-VLA；改用 WLA/Qwen Apache 底座。
10. **外部数据/模型不允许**：只用挑战数据；做“仅挑战数据”的消融。

### S.2 必须确认的问题（按优先级）

1. Feishu 2.3–5.2 的完整规则（外部数据/模型、控制频率、评分公式、硬编码限制、base/waist 限制）。
2. N 的具体值；多端口共享后端/健康检查/重连规则。
