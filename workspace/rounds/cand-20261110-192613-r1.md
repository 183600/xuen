# 第 47 轮（承接第 46 轮 v23；本轮灵感：机器人操作系统 × 奖励设计） · ROS-Cert：QoS 证书总线与安全支配奖励合约的联合保证（架构 v11）

> 承接第 46 轮 v23 Memory-Safety-Voice。v23 把记忆检索、语音分发、安全绑定串成全局决策 Π，但隐含假设 H5：**证书与决策信号在分布式系统中的传递是瞬时、无损、可信的，且效用函数 U 的设计不会与安全目标冲突**。UniBot 的实机软件栈是 ROS 2（节点 / 话题 / 生命周期 / DDS QoS），四路 RGB、双目、深度、语音、机械臂控制分布在不同节点与执行器上；真实系统里证书会因 deadline 错过、lifespan 过期、节点重启、DDS 发现延迟而静默变旧，而 U(m) 是手调权重，奖励项之间可被“刷分”。两个灵感词精确命中 H5：**机器人操作系统**把证书/租约从进程内对象升级为受 QoS 约束的分布式能力，使“图本身”成为需要被认证的对象；**奖励设计**把效用从手调权重升级为带合约的多目标奖励，并暴露奖励黑客（reward hacking）这一新的失效通道。二者耦合出的新问题：**当承载奖励项或安全项的 ROS 节点掉线/消息过期时，仲裁器可能用“看起来健康”的陈旧奖励去优化代理指标，从而在证书已失效的情况下继续执行，安全保证被静默击穿**。

## 0. 直觉与动机

**灵感 1（机器人操作系统 → 证书即 QoS 能力）**
直觉：现在的姿态证书 P_t、能量租约 ℓ_e、安全绑定 B 都是“消息里的数字”，但消息可能迟到、丢失、来自一个已经被 lifecycle 停用的节点。ROS 2 的 QoS（reliability / durability / deadline / lifespan / liveliness）恰好描述了“这条消息还能不能被信任”。于是证书不再是一个裸结构体，而是带发布者身份、发布时间、deadline 与 lifespan 的**能力令牌**；消费者只有在“按时送达且生产者活着”时才允许使用它。更进一步，安全保证依赖从传感器到 CAR 的整条链，单条消息健康不代表整条图健康，因此需要一张**端到端图证书 Graph-Cert**。

**灵感 2（奖励设计 → 安全支配的奖励合约）**
直觉：U(m) 里的权重是人拍的，容易被代理指标带偏（比如“深度开启时长”不等于“证书变窄”）。更危险的是，如果把安全当成一个可加权项，优化器一定会用安全换任务分。正确做法是把安全项设为**硬约束 / 字典序支配**，任务与能耗项才可加权；同时任何奖励项都必须带“可验证合约”：它在独立审计集上确实与真实结局同向，且不存在明显的代理刷分通道（有界代理间隙），shaping 还必须写成势函数形式以免改变最优策略。

**灵感 3（耦合 → 分布式奖励 + 图证书）**
直觉：奖励项来自 ROS 图里的不同节点（任务规划、能量管理、安全监控），它们各自有 QoS 与新鲜度。仲裁器不能假设它们永远可信。于是仲裁变成“先验合约、再验 QoS、最后优化”的三段式：合约不成立或信号过期 → 该奖励项作废；若作废的是安全项 → 直接 fail-closed，而不是退回一个仍然偏任务分的基线效用。

**耦合升级**：在 v23 之上新增 **ROS 证书总线层** 与 **奖励合约层**。QCB 把证书/租约变成 QoS 标注的生命周期能力并认证端到端图；RCA 用安全支配的字典序奖励组合各节点信号；RHA 对奖励项做反黑客审计。v11 分层：根信任层增加 QoS 租约与图证书，L1 几何层不变但证书消费受 QoS 门控，L2 上下文/记忆层仅在合约有效时复用，L3 CAR 守卫消费 Graph-Cert，L4 采集层收集奖励合约审计与延迟轨迹。

## 1. 形式化定义（增量：定义 59–63）

**定义 59（QoS 证书能力）**
能力 κ=(n, τ, q)，n 为节点，τ 为话题，q=(reliability, durability, deadline d, lifespan L, liveliness)。证书消息 c 在消费者时刻 t 可用当且仅当
Delivered(c,t) ∧ (t − t_pub(c)) ≤ L ∧ alive(n_pub,t) ∧ latency(c) ≤ d。
满足时称 c 是 **QoS 有效**的，记 Valid_q(c,t)=1。QoS 有效的证书才可进入姿态/能量/安全谓词。

**定义 60（端到端图证书 Graph-Cert）**
设安全关键链为有向无环图 G=(V,E)，从传感器节点到 CAR 守卫。每条边 e 有最坏时延上界 w_e 与丢包上界 p_e；端到端预算 D_φ。图证书
Γ_G=(G, {w_e}, {p_e}, D_φ, α_g)
保证 P(关键消息在 D_φ 内无丢失送达 ∧ 所有中间节点存活) ≥ 1−α_g。
若 Γ_G 失效（deadline miss、丢包超界、节点重启），则所有下游租约被**原子撤销**。

**定义 61（安全支配奖励合约）**
奖励分解 R=Σ_k w_k r_k，按语义分为安全项 R_S、任务项 R_T、资源项 R_E。策略只在安全可行集内优化：
Π_safe={π : E[Violations(π)] ≤ ε}，
π* ∈ argmax_{π∈Π_safe} E[R_T − R_E]。
安全项不参与加权折中，而是作为硬约束；任何 shaping 项 F 必须满足势函数形式 F(s,s')=γΦ(s')−Φ(s)，以保证不改变最优策略（Ng et al. 1999）。

**定义 62（奖励合约有效性与代理间隙）**
奖励项 r_k 关于真实结局 o 的合约有效，当且仅当在独立审计分布 D_aud 上
r_k↑ ⇒ o↑（统计显著），
且**代理间隙**有界：
Gap(r_k)=max_{π∈Π_adv, E[o]≤o_0} E_π[r_k] ≤ δ_k，
即不存在“奖励涨、真实结局不涨”的可利用策略。再叠加新鲜度：reward_age ≤ L_r。合约有效且新鲜才允许参与仲裁。

**定义 63（ROS-奖励联合决策）**
仲裁器 A 每周期收集各节点奖励项及其合约/QoS，仅组合 **合约有效且 QoS 新鲜** 的项。若被剔除的是安全相关项，或 Γ_G 失效，或任一安全项 reward_age > L_r，则 A 不退回“仍然优化任务分的基线”，而是进入保守模式：强制 m 含 Depth 或直接 fail-closed。决策
m_t = argmax_{a∈A_feasible} R_composed(a)，s.t. 安全约束与 Γ_G 均成立。

## 2. 三大新增产出与既有 IP 升级

**IP-69 QCB（QoS Certificate Bus）**
- 证书/租约的 QoS 标注与生命周期节点封装
- 端到端 Graph-Cert 认证：deadline / loss / liveliness 监控
- 原子撤销：任一上游失效 → 下游租约级联失效
- 证书审计日志与回放

**IP-70 RCA（Reward Contract Arbiter）**
- 安全支配的字典序奖励组合
- 势函数 shaping 校验
- 合约有效性 + 新鲜度门控
- 安全项缺失时 fail-closed，而非基线回退

**IP-71 RHA（Reward Hack Auditor）**
- 代理间隙搜索（对抗策略）
- 独立审计集与合约违约检测
- 违约样本回灌 DCL/CCA
- 奖励项相关性/共线性检查

**既有 IP 升级**
IP-45 总线：升级为 ROS 2 QoS 图 + lifecycle + Graph-Cert / revoke 话题
IP-51 CAR：消费 Γ_G 与 QoS 有效租约，deadline miss 即撤销
IP-62 CCA：新增节点 kill/restart、QoS 降级、奖励黑客红队
IP-63 ECPS：效用改由 RCA 组合奖励驱动
IP-66 MVR：记忆命中仅在合约/QoS 新鲜时可用
IP-61 DCL：采集延迟轨迹与奖励合约审计样本

## 3. 算法骨架

QCB 持续维护：
1. 订阅证书/租约话题，记录 t_pub、deadline、lifespan、publisher liveliness
2. 计算端到端延迟与丢包，更新 Γ_G
3. 任一失效 → 发布 revoke 并级联
RCA 每控制周期：
1. 收集奖励项 r_k 及其 contract、reward_age、QoS
2. 过滤合约无效或过期的项
3. 若安全项被过滤或 Γ_G 失效 → fail-closed / 保守模式
4. 否则字典序：先满足安全约束，再 argmax R_T − R_E
5. 输出 m_t 给 ECPS/PSE/CAR
RHA 离线/在线：
1. 对每个 r_k 在 D_aud 上估计 Gap(r_k)
2. 超 δ_k 或与安全项高相关 → 标记违约并回灌

## 4. 本轮最大风险

**一句话**：RCA 可能组合出一组“单看每项合约都有效、QoS 也都新鲜”的奖励，但它们彼此相关或共同依赖同一个被投毒的节点，从而在某个安全信号恰好迟到/丢失的窗口里把策略推向代理指标，证书静默失效；因此安全项必须在奖励之外以硬约束与图证书双重强制执行，且任何安全项失效都应 fail-closed 而不是回退到仍优化任务分的基线。

## 2. 关键算法 伪代码

### IP-69 QCB
```
def qos_valid(cert, t):
    return (cert.delivered and
            t - cert.t_pub <= cert.qos.lifespan and
            alive(cert.publisher, t) and
            cert.latency <= cert.qos.deadline)

def update_graph_cert(G, traces, D_phi, alpha_g):
    for e in G.edges:
        w_e = percentile(traces[e].latency, 99.9)
        p_e = mean(traces[e].loss)
    ok = all(w_e <= D_phi_budget[e]) and sum(p_e) <= alpha_g
    if not ok:
        publish('/cert/revoke', G.critical_nodes)  # 原子撤销下游租约
    return GraphCert(G, {w_e}, {p_e}, D_phi, ok)

def consume_lease(lease, t, graph_cert):
    if not graph_cert.ok:      # 图失效，任何下游租约都不可用
        return None
    if not qos_valid(lease, t):  # 单条消息过期/迟到/生产者失活
        return None
    return lease.payload
```

### IP-70 RCA
```
def reward_contract_valid(rk, audit):
    if not direction_test(rk, audit):     # r_k↑ ⇒ o↑ 统计显著
        return False
    if proxy_gap(rk, audit) > rk.delta:   # 代理间隙超界
        return False
    return True

def compose_reward(terms, t, audit):
    safe, task, res = [], [], []
    for rk in terms:
        stale = t - rk.t_sig > rk.L_r
        if stale or not reward_contract_valid(rk, audit):
            if rk.is_safety:
                return None, 'safety_term_invalid'   # 安全项不可降级
            continue
        (safe if rk.is_safety else
         task if rk.is_task else res).append(rk)
    if not safe:
        return None, 'no_safety_term'
    return SafeLexReward(safe, task, res), 'ok'

def rca_decide(terms, actions, t, graph_cert, audit):
    if not graph_cert.ok:
        return fail_closed('graph')
    R, status = compose_reward(terms, t, audit)
    if R is None:
        return fail_closed(status)          # 不回退任务分基线
    feasible = [a for a in actions if R.safety_ok(a)]
    if not feasible:
        return fail_closed('no_feasible')
    return max(feasible, key=lambda a: R.task(a) - R.res(a)), status
```

### IP-71 RHA
```
def proxy_gap(rk, audit, o0):
    adv = search_adversarial_policy(
        rk, constraint=lambda pi: E_o(pi) <= o0)
    return E(adv, rk)

def audit_reward_terms(terms, audit, rho_max=0.8):
    violations = []
    for rk in terms:
        g = proxy_gap(rk, audit, o0=rk.o0)
        corr = corr_with_safety(rk, terms)
        if g > rk.delta or corr > rho_max:
            violations.append((rk.id, g, corr))
            push_to_DCL(rk.id, audit.samples)
    return violations
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| QCB 图证书更新 | O(|E|) 每窗口 | O(|E|+|V|) | 所有边满足 deadline/丢包界 ⇒ Γ_G 有效 |
| RCA 仲裁 | O(|terms|·|A|) 每周期 | O(|terms|) | 仅组合合约有效且新鲜项；安全项硬约束 |
| RHA 审计 | O(|terms|·cost(adv)) | O(|terms|·|D_aud|) | 代理间隙 > δ 或高相关 ⇒ 违约 |
| 全局决策 Π' | O(|M|+|terms|·|A|) | O(|Q|) | 图/合约/能量/绑定四重门控 ⇒ fail-closed |

正确性定理：若 Γ_G 有效且所有安全项合约有效、reward_age ≤ L_r，则 RCA 输出的 m_t 属于安全可行集 Π_safe，且被消费的租约均 QoS 有效，姿态/能量/安全谓词的 soundness 得以保持；反之，若 Γ_G 失效、任一安全项无效/过期、或可行集为空，则 Π' 返回 fail-closed（或保守 Depth-On 模式），不会执行任何仍优化任务分的动作。势函数 shaping 保证奖励改造不改变最优策略。

| 审计过严导致频繁 fail-closed | 中 | δ/ρ 自适应但安全优先，允许保守 Depth-On 而非放开约束 |

## 6. 本轮最大风险

**一句话**：RCA 可能组合出一组“单看每项合约都有效、QoS 也都新鲜”的奖励，但它们彼此相关或共同依赖同一个被投毒的节点，在某个安全信号恰好迟到/丢失的窗口把策略推向代理指标，证书静默失效；因此安全项必须在奖励之外以硬约束与图证书双重强制执行，且任何安全项失效都应 fail-closed 而不是回退到仍优化任务分的基线。
