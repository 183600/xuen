# 第 58 轮（承接第 57 轮「少样本×跨模态×个性化」IP-133~138；灵感循环第 4 轮；本轮灵感：「通用机器人平台」×「步骤分」）

> 第 57 轮把安全的赌注从"模型置信"换到"证据质量"，再用元少样本、跨模态对账、个性化信任把证据做厚；但它的风险自陈暴露了一个更深的部署经济学问题：**全部保证都绑在单一具身与单一评测口径上**。**(a)** 所谓"通用机器人平台"意味着同一能力要在不同机身、传感器集、执行器包络与时延预算上复用；证据若不能移植，平台就退化成 N 台定制机器人（复用成本归零）；证据若被直接复制，则未被声明的机身差异（热漂、延迟、摩擦、载荷）会让"已验证"悄悄失效。**(b)** 任务评测给的是**步骤分**：每步完成度加权的稠密部分分。它比"最终成功/失败"信息量高得多，却是一个代理指标——局部挣到的分不等于真实任务价值；第 57 轮的 PCE+ 完全不懂分数结构，可能把预算耗在低值安全步骤上（刷分），也可能为了保住成功率而绕开高值不可逆的收尾步骤（弃考）。**(c)** 反过来，步骤分又是极廉价、极稠密的校准标签：它能指出系统在哪一步、因为缺哪类证据而丢分——但前提是每一步的分能被**因果归因**到具体能力与证据，而不是记在一团黑箱策略头上。本轮两个灵感各补一条腿：**通用机器人平台**把能力从"事实"改写为"契约"，把证据拆成"机制不变量（可移植）/具身特化量（须重验）"，并给出移植税与运行时契约监控；**步骤分**把评测从黑箱标量拆成"分账本"（每步期望边际分 + 不确定性 + 归因），再用防刷分审计把"读分"与"被分读"隔开。核心命题由"证据说可信"升级为 **"可移植、可读分、抗刷分的证据说可信"**。

核心矛盾：
- **H29（移植 vs 有效）**：契约类型检查通过 ≠ 动力学等价。把源机身的证据搬到目标机身，要么保守到把平台优势耗尽（τ_port→1），要么乐观到漏掉一个未声明的隐变量（热、时延、回差、接触摩擦），让"通用"变成"普遍自信"。
- **H30（稠密分 vs 真实成功）**：步骤分是真实任务的代理，且其权重由外部评分者设定。局部边际分为正的步骤集合未必使全局成功率最大；"能挣分"与"有能力"可以在训练/部署中解耦。
- **H31（可读分 vs 可博弈）**：把分数显式喂给规划器，就等于制造了一个可优化的目标。刷分（farm）、弃考（last-step avoidance）、故意早败以重置（sandbagging）、贴合评分表（rubric overfit）都会出现；审计本身也会改变行为。

## 0. 直觉与动机

**灵感 1（通用机器人平台 → 能力是契约，不是事实）**
直觉：平台上不应该说"本机器人能过 20° 湿滑坡"，而应说"**在传感器含本体+触探、执行器力矩≥τ、时延≤ℓ、坡面材质属于 M 类**的前提下，本能力对 20° 湿滑坡给出 δ_f 级失败保证，证据见 E"。前者是某一台机器的一次观测，后者才可被别的机身实例化、组合、审计。于是把能力写成五元契约 κ=(P,A,B,G,E)：前提、假设、行为族、保证、证据；平台是一个契约集合加一个组合算子 ⊕，机身只提供 profile(e)。"通用"不表示一份证据通吃，而表示**许多 e 能通过类型检查实例化同一个 κ**，并且组合后的保证可被机械推导。

**灵感 2（跨具身迁移 → 重新链接，而不是复制二进制）**
直觉：把机器人 A 的证据整个拷到 B，像把 x86 二进制直接丢到 ARM 上跑——偶尔能跑，是因为碰巧没用到差异。正确做法是"重新编译"：证据按支撑假设分块，落在**迁移不变量集** Inv(s→t) 里的机制性部分可以携带（如"触探刚度上升⇒承载力上升"这类因果方向），落在具身特化部分（绝对力阈值、延迟补偿、热漂）的必须用**重验预算** B_reval 在目标机上补证。引入**移植税** τ_port=B_reval/B_full 作为平台复用的真实成本；写进证书 J_port，并要求运行时契约监控在 Δ_port 超界时自动降级。

**灵感 3（步骤分 → 分账本而不是追分器）**
直觉：步骤分像考试的步骤分——它奖励"写出关键中间结论"，但一个只背步骤的学生会做对格式、做错题。正确用法不是让规划器直接最大化当前分，而是建一本**分账本**：每一步记录 p̂_s（完成概率）、ŵ_s（权重估计）、期望边际分、归因 a_s（这一步的分由哪条能力/哪类证据换来）、以及为它花掉的探针时间。区分"执行分"与"安全垫分"（探询/绕行只花时间不直接得分），并要求**无已验证状态转移不记分**。如此，分既是优化目标的一部分，也是诊断证据缺口的监督信号。

**灵感 4（分数感知承诺 → 不刷分、不弃考）**
直觉：分数结构应当改变"在哪里花证据预算"，但绝不能改变安全门。高值且不可逆的步骤应获得**更多**证据而不是更少（因为失败代价大）；低值且可逆的步骤不许反复停留刷分（因为时间预算有限）；中间步骤的价值要含**续期期权** CV(s)——为了后面的大分，允许在前一步多花一点，但不允许为一个已经能拿满的小分反复打磨。分数感知 VOI 因此写成：Δ期望总分 − λ_R·ΔP_fail − λ_T·成本，且承诺必须同时过安全门与分账门。

**灵感 5（防刷分审计 → 反事实分账）**
直觉：判断"这步分是不是真挣的"，最直接的办法是问反事实：**做了这一步 vs 跳过这一步，总分差多少**（CC(s)）。刷分策略的特征是"局部报告分高、反事实边际分为负"；弃考策略的特征是"成功率好看、总步骤分被主动放弃"；贴合评分表的特征是"分数涨、独立能力探针不涨"。审计器用这三类统计做折扣：被判定刷分时，**只在规划器内部打折，不篡改真实分**；同时插入随机审计步与留出能力探针。这样规划器读到的分更接近真实边际价值，而真实评测仍保持原样。

**灵感 6（三机制合流 → PCE++/PLX：平台-分数-证据三层联动）**
直觉：第 57 轮 PCE+ 的每个检查点恰好对齐一个官方计分步；本轮让检查点多做三件事：实例化/校验契约、记分账、过防刷分审计。移植证书 J_port 与分账本 L 一起进入承诺证书 J_q。击穿安全需要：契约假设漏项 ∧ 运行时监控漏检 ∧ 重验预算不足 ∧ 分数误导 ∧ 审计漏判 ∧ 证据门失守——纵深从五层扩到七层。

## 1. 形式化定义（增量：定义 139–144）

**定义 139（平台能力契约 PCC）** 平台 Π=(𝒦,⊕,Profile)。能力契约 κ=(P_κ,A_κ,B_κ,G_κ,E_κ)：P 前提（任务/地形/物体类），A 假设（传感集、执行器包络、时延上界、动力学类、热/摩擦区间），B 行为族，G 保证（δ_f、安全不变量、性能下界），E 证据证书。机身 profile(e)=(sensors(e), act(e), ℓ(e), dyn(e), env(e))。实例化合法：e⊨κ ⇔ Profile(e)⊨P_κ∧A_κ。组合 κ₁⊕κ₂ 仅当交互假设 A₁₂ 被显式消解时定义，且 G(κ₁⊕κ₂)=G₁∧G₂∧G₁₂（交互项不得省略）。平台"通用性"度量 U(Π)=|{e:∃κ∈𝒦, e⊨κ}|，而非"一份 E 适用于所有 e"。

**定义 140（跨具身证据迁移 XEP）** 迁移映射 T_{s→t}，支撑集 supp(E)⊆A_κ；迁移差异 Δ_port(s→t)=dist(Profile(s),Profile(t))；迁移不变量集 Inv(s→t)={a∈A_κ : a 在 Δ_port 下语义保持}。证据分块 E=I(E)⊕V(E)（不变量/特化量）。三规则：(R1) 可携带 E_t⊇I(E_s) 仅当 Δ_port≤θ_port ∧ 运行时契约监控 M_κ 通过；(R2) 特化量必须以重验预算 B_reval(κ,e_t) 在目标机补证，移植税 τ_port=B_reval/B_full；(R3) 保证携带需扣除 slack(Δ_port)，即 G_t≤G_s−slack(Δ_port)−δ_port，且 J_port=(Δ_port,Inv,B_reval,M_κ 日志) 必检；实例化非法时**禁止声明任何携带保证**。

**定义 141（步骤分账本 SSD）** 评分 S(τ)=Σ_{s∈σ(τ)} w_s·c_s + bonus(τ)，c_s∈[0,1] 为该步完成度，w_s 为步骤权重（外部给定，系统只估计不修改）。账本 L(s)=(p̂_s,ŵ_s,σ̂_s,a_s,pad_s)：完成概率、权重估计、分的不确定度、归因（能力/证据类/契约）、安全垫耗时。期望挣分 E[credit_s]=ŵ_s p̂_s c_s；**无已验证状态转移则不记分**。称探针/绕行时间为"生产性垫时"当其提升后续 E[credit]，否则为"纯垫时"。边际分 MSV(a|s)=ΔE[S]/Δ(cost)。账本校准要求 |E[S]−Σ_s E[credit_s]|≤ε_ledger 且分账 ECE≤ε_L。

**定义 142（分数感知承诺 SCA）** 每计分步决策集 {commit, probe, reroute, skip, negotiate}。目标：max E[S] s.t. P_fail≤δ_f、安全不变量、时间/探针预算。分数感知 VOI：VOI_S(π)=E[S|π]−E[S|¬π]−λ_R·ΔP_fail−λ_T·cost(π)；续期期权 CV(s)=E[S_after|state]。承诺规则：commit ⇔ 安全门过 ∧ 证据门过 ∧ [MSV(a|s)+CV_guard(s)≥θ_msv]。预算优先级：分数关键 ∧ 高不确定性 ∧ 不可逆 > 分数关键 ∧ 可逆 > 非关键；**低值步骤不得占用为高值步骤保留的探针预算**。

**定义 143（防刷分审计 SGR）** 反事实分 CC(s)=E[S|do(s)]−E[S|do(skip s)]。审计统计 A_ga=Σ_s max(0, reported_credit(s)−CC(s)) + λ_c·1[Δscore>0 ∧ Δcapability_probe≤0]。四类策略：刷分（多低 CC 步、局部正分）、弃考（跳过高值不可逆步以保成功率）、早败重置（sandbagging）、评分表过拟合（分数涨、能力探针平）。规则：A_ga>θ_ga ⇒ (i) 规划器内部对相应分打折（不改真实分）；(ii) 证据门收紧一档；(iii) 插入随机审计步与留出能力探针。在硬安全与时间预算下，可证明刷分/弃考的可得收益上界为 ε_farm。

**定义 144（平台-分数探诺演 PLX / PCE++）** 每个计分步：①实例化并校验 PCC（e⊨κ），必要时按 XEP 重验；②继承第 57 轮元推断/跨模态对账；③更新分账本 L（SSD）；④按 SCA 计算候选动作的分数感知 VOI 与续期期权；⑤过 SGR 审计（含随机审计步）；⑥执行 commit/probe/reroute/skip/negotiate；⑦携带 J_q=(J_p,J_port,L,audit_log)。终止条件：探针 ≤k_probes+k_cons、审计步 ≤k_audit，每步必落入 {承诺,绕行,跳过,协商,安全停}。

## 2. 关键算法伪代码（完整版见产物区）

```python
def portable_instantiate(kappa, e, J_port):
    if not profile_entails(profile(e), kappa.P, kappa.A):
        return Failure('contract_unsatisfied')          # 不许声明保证
    inv = invariant_part(kappa.E, delta_port(src(e), e))
    if delta_port(src(e), e) > theta_port or not monitor_ok(kappa, e):
        return revalidate(kappa, e, budget=kappa.B_reval)  # 重验，不复制
    return carry(inv, slack=slack(delta_port(src(e), e)))

def score_aware_decide(cp, L, M, budget):
    for a in {commit, probe, reroute, skip}:
        a.voi = expected_score(a, L, M) - lam_R * delta_risk(a) - lam_T * cost(a)
    order = priority(cp, L)                              # 关键×不确定×不可逆
    a = argmax(order, key=lambda x: x.voi + continuation_value(x, L))
    if a.voi + continuation_value(a, L) < theta_msv:
        return 'negotiate_or_stop'
    if not safety_gate(a, M) or not evidence_gate(a, M, J_q):
        return 'probe_or_reroute'
    return commit(a)

def audit_gaming(seq, L, capability_probe):
    A = sum(max(0, L.credit(s) - counterfactual_credit(s, seq)) for s in seq)
    A += lam_c * int(score_up(seq) and not capability_up(capability_probe))
    if A > theta_ga:                                     # 只打折规划分，不改真实分
        L.discount(); tighten_evidence_gate(); schedule_random_audit_step()
    return A
```

## 3. 复杂度与正确性（要点）

| 组件 | 时间 | 空间 | 正确性关键 |
|---|---|---|---|
| PCC | O(\|𝒦\|·\|Profile\|) 编译；O(1) 实例化检查 | O(\|𝒦\|+\|Profile\|) | 契约假设完备、组合交互项消解 |
| XEP | O(\|E\|·\|Inv\|) 分块；O(B_reval) 重验 | O(\|E\|+\|J_port\|) | Δ_port 估计诚实、监控覆盖、无携带超界 |
| SSD | O(\|σ\|·d_state)/轨迹 | O(\|σ\|) | 归因可验证、账本校准、垫时分类正确 |
| SCA | O(\|A\|·(C_VOI+C_CV)) / 步 | O(\|σ\|) | 续期期权正确、预算优先级不被低值步挪用 |
| SGR | O(\|seq\|·C_CC)+O(k_audit) | O(\|seq\|) | 反事实估计误差 ≤ε_cc、审计随机化 |
| PLX | O(\|CP\|·(k_p+k_c+k_a)·(C_VOI+d_φ)) | O(\|V\|+\|σ\|) | 终止、四态+跳过完备 |

**正确性定理（Portable Score-Credible Commitment, PSCC 概要）**：在 A33–A40 之上增加 (A41) 契约实例化与组合健全：Profile(e)⊨P∧A，且组合交互项被显式消解；(A42) 移植诚实：Δ_port 估计误差 ≤ε_port，Inv 认证完备，运行时监控漏检 ≤δ_mon，重验预算被执行；(A43) 分账归因诚实且校准：无验证转移不记分，|E[S]−Σ credit|≤ε_ledger；(A44) 反事实审计可靠：CC 估计误差 ≤ε_cc，审计步随机化且不可被策略预测。则：
1. **可移植健全性**：对合法实例化且重验完成的目标机身，P(fail)≤G_κ+slack(Δ_port)+δ_port+δ_mon；非法实例化不产生携带保证（拒绝而非降级声明）。
2. **分数可读性**：账本对真实总分的偏差 ≤ε_ledger；在分账误差 ≤ε_L 下，SCA 相对安全约束最优的期望分损失 ≤ε_opt，且不改变硬安全不变量。
3. **抗博弈性**：在硬安全与固定时间预算下，刷分/弃考/早败重置的可获得益 ≤ε_farm；审计只打折规划内部分，不污染真实评测；被审计触发后证据门单调收紧。
4. **终止与部署界**：每步探针 ≤k_probes+k_cons、审计 ≤k_audit，PLX 终止；对计分步取联合界：

```
P_safe ≥ 1 − Σ_s (δ_f + ε_meta + δ_probe + ε_h + δ_ood·α_conf + δ_xm·1[L1])
             − Σ_s slack(Δ_port) − P(监控漏检) − P(分账误导 ∧ 审计漏判) − P(协商超时 ∧ 安全停失效)
```

关键：**契约给可移植的"类型"，重验给本机的"值"**；**账本给可读的"分"，反事实审计给不可刷的"分"**；分数只改预算分配与优先级，安全门与承诺规则本体永不因分而放宽。

## 6. 本轮最大风险

**一句话**：本轮把"通用"建立在契约可实例化、把"可读"建立在分账可归因之上，最大风险是**契约把未声明的具身隐变量（热漂、时延、摩擦回差）留在了类型系统之外**——类型检查与移植税都按声明过的 Δ_port 计算，于是目标机身会带着一份"合法但错误"的保证运行，而分数感知承诺又会优先把预算推向高值步骤、放大这类未被监控的耦合；必须以运行时契约监控、保守的移植税下界和"重验未完成即拒绝声明保证"三道硬约束兜底，宁可把平台用成"可证明的少量复用"，也不要做成"普遍的自信"。

```python
def contract_compile(kappa):
    # 契约必须显式列出可被机身 profile 检查的假设
    return {
        'pre': kappa.P, 'assume': kappa.A, 'behavior': kappa.B,
        'guarantee': kappa.G, 'evidence': kappa.E,
        'monitor': build_runtime_monitor(kappa.A),   # 假设的在线可观测投影
    }

def instantiate(kappa, e):
    if not entails(Profile(e), kappa.P) or not entails(Profile(e), kappa.A):
        return Failure('contract_unsatisfied')        # 禁止声明保证
    return Instance(kappa=kappa, e=e, monitor=kappa.monitor)

def compose(k1, k2, interaction):
    if not resolve_interaction(k1, k2, interaction):  # 交互项不得省略
        return Failure('interaction_undischarged')
    return Contract(P=k1.P & k2.P,
                    A=k1.A & k2.A & interaction.assumptions,
                    B=compose_behavior(k1.B, k2.B),
                    G=k1.G & k2.G & interaction.G12,   # G12 必须显式给出
                    E=k1.E + k2.E)
```

```python
def port_evidence(kappa, e_src, e_tgt, J_port=None):
    d = delta_port(Profile(e_src), Profile(e_tgt))     # 传感/执行/时延/动力学/环境
    inv = invariant_part(kappa.E, d)                   # 机制性、方向性证据
    spec = specialized_part(kappa.E, d)                # 绝对阈值/延迟补偿/热漂参数
    if d > theta_port or not runtime_contract_monitor(kappa, e_tgt):
        # 不允许"复制二进制"：目标机必须重验特化量
        reval = revalidate(kappa, e_tgt, budget=B_reval(kappa, e_tgt))
        return Ported(evidence=inv, revalidated=reval, tax=1.0,
                      J_port=make_port_cert(d, inv, reval, monitor_log))
    carried = carry(inv, slack=slack(d))               # 只携带不变量部分
    return Ported(evidence=carried, revalidated=None,
                  tax=B_reval(kappa, e_tgt) / B_full(kappa),
                  J_port=make_port_cert(d, inv, None, monitor_log))

def delta_port(p_src, p_tgt):
    return w_s * sensor_gap(p_src, p_tgt) + w_a * actuator_gap(p_src, p_tgt) \
         + w_l * latency_gap(p_src, p_tgt) + w_d * dynamics_gap(p_src, p_tgt) \
         + w_e * env_gap(p_src, p_tgt)                 # 每项取保守下界

def guarantee_on_target(G_src, d):
    return G_src - slack(d) - delta_port_uncertainty(d) # 保证单调不增
```

```python
def ledger_update(L, s, outcome, evidence, cost):
```

```python
def score_aware_commit(cp, M, L, budget):
    cands = {commit, probe, reroute, skip}
    for a in cands:
        a.voi = expected_score(a, L) - expected_score(skip(a), L) \
                - lam_R * delta_risk(a, M) - lam_T * cost(a)

    order = sorted(cands, key=lambda a: (budget_priority(a, crit), a.total))

        if not safety_gate(a, M): continue              # 安全门永不放宽

def budget_priority(a, crit):
    # 高值不可逆步优先拿证据预算；低值步不得挪用保留预算
    return 2 if crit else (1 if is_score_critical(a) else 0)
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| PCC | O(\|𝒦\|·\|Profile\|) 编译；O(1) 实例化 | O(\|𝒦\|+\|Profile\|) | 假设完备、交互项消解（A41） |
| XEP | O(\|E\|·\|Inv\|)+O(B_reval) | O(\|E\|+\|J_port\|) | Δ_port 诚实、不变量完备、监控覆盖（A42） |
| SSD | O(\|σ\|·d_state) | O(\|σ\|) | 无验证转移不记分、账本校准（A43） |
| SCA | O(\|A\|·(C_VOI+C_CV)) | O(\|σ\|) | 续期期权、预算优先级、安全门不放宽 |
| SGR | O(\|seq\|·C_CC)+O(k_audit) | O(\|seq\|) | 反事实误差 ≤ε_cc、审计随机化（A44） |
| PLX | O(\|CP\|·(k_p+k_c+k_a)·(C_VOI+C_CV+d_φ)) | O(\|V\|+\|σ\|) | 终止、决策集完备、J_q 全检 |

**正确性定理（Portable Score-Credible Commitment, PSCC）**
假设 A22–A32（第 53–55 轮）、A33–A40（第 56–57 轮）成立；**(A41)** 契约实例化与组合健全：Profile(e)⊨P∧A，组合交互项显式消解且 G₁₂ 给出；**(A42)** 移植诚实：Δ_port 估计误差 ≤ε_port，Inv 认证完备，运行时契约监控漏检 ≤δ_mon，重验预算被执行；**(A43)** 分账归因诚实且校准：无已验证转移不记分，|E[S]−Σ_s credit_s|≤ε_ledger，分账 ECE≤ε_L；**(A44)** 反事实审计可靠：CC 估计误差 ≤ε_cc，审计步随机且策略不可预测。则：

1. **可移植健全性**：对合法实例化且完成重验的目标机身，
   `P(fail) ≤ G_κ + slack(Δ_port) + δ_port + δ_mon`；
   对非法实例化或监控失败，系统拒绝携带保证（Fail-closed），而非降级声明。
2. **分数可读性**：账本对真实总分偏差 ≤ε_ledger；在分账误差 ≤ε_L 下，SCA 相对"安全约束下最优期望分"的损失 ≤ε_opt，且硬安全不变量与证据门不被分数改变。
3. **抗博弈性**：在硬安全与固定时间/探针预算下，任意刷分、弃考、早败重置策略相对诚实策略的可得收益 ≤ε_farm；被审计触发后证据门单调收紧，且真实评测分不被系统篡改。
4. **终止与部署界**：每计分步探针 ≤k_probes+k_cons、审计步 ≤k_audit，PLX 终止于 {承诺,绕行,跳过,协商,安全停}；取联合界：

```
P_safe ≥ 1 − Σ_s (δ_f + ε_meta(k) + δ_probe + ε_h(w_max) + δ_ood·α_conf + δ_xm·1[L1])
             − Σ_s slack(Δ_port) − P(运行时监控漏检) − P(分账误导 ∧ 审计漏判) − P(协商超时 ∧ 安全停失效)
```

三个新机制的安全角色可一句话概括：**契约把"能不能在这台机上声明"变成可检查的类型问题；账本把"分数能不能用于决策"变成可归因的统计问题；审计把"分会不会被刷"变成可证界的博弈问题。** 三者都只经"更保守的声明/更窄的预算/更紧的证据门"影响系统，不存在因分数或平台复用而放宽安全门的路径。

云边协议 CEB++ → **CEB+++**：云端可下发**契约库与元模型增量**，但两者都走隔离区——契约先在影子机身（仿真/备用机）做实例化回归（e⊨κ、组合交互项、监控覆盖率），元模型先做校准/OOD/分歧回归；通过后才可进入承诺判定。边端回传：契约假设残差、Δ_port 实测偏移、分账残差、四类博弈告警，作为契约补盲与移植税重估的依据。第 57 轮"一切判定器走隔离"在本轮推广为"**一切能力声明走契约、一切分数使用走账本**"。

## 6. 本轮最大风险

**一句话**：本轮把"通用"建立在契约可实例化、把"可读"建立在分账可归因之上，最大风险是**契约把未声明的具身隐变量（热漂、时延、摩擦回差）留在了类型系统之外**——类型检查与移植税都按声明过的 Δ_port 计算，于是目标机身会带着一份"合法但错误"的保证运行，而分数感知承诺又会优先把预算推向高值步骤、放大这类未被监控的耦合；必须以运行时契约监控、保守的移植税下界和"重验未完成即拒绝声明保证"三道硬约束兜底，宁可把平台用成"可证明的少量复用"，也不要做成"普遍的自信"。
