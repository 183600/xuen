# 第 55 轮（承接第 54 轮 v31 GroundEdge-GenSim+++；新灵感循环第 2 轮；本轮灵感：「动作空间」×「容错控制」）· FaultGround：方向性可生存 × 诊断条件化容错证书

> 第 54 轮把技能组合推进到动作剖面 `α_S`、组合图 `G_S` 与云边联合证书 `J=(ρ,A_cert,γ_ce,δ_a)`。但该体系默认动作空间是**标称、静态、故障无关**的：`α_S` 标定一次，`compat` 用体积 Jaccard，证书只在“无故障”前提下签发。容错控制正面击穿这三个默认：故障不是“技能变差一点”，而是**同一指令的效果映射 `φ` 被改写**——失效、饱和、卡死执行器会让动作空间缩小、平移，甚至沿任务关键方向塌缩；传感器故障则让 `α_S` 与 `ρ` 的估计本身失真。本轮核心命题：**动作空间必须按故障模式条件化；容错不是给标称证书加 fallback，而是证书有效域的第二维。** 三个核心矛盾：**H24** 体积兼容 ≠ 方向可生存；**H25** 证书的“有效”是故障条件化的，而诊断有延迟、漏检与未知故障；**H26** 恢复动作本身有暂态，可能制造二次故障。

## 0. 直觉与动机

**灵感 1（动作空间是效果空间，不是指令空间）**
直觉：同一句“向前推 1 N”，在三个推进器都正常时产生前向力；坏掉一个推进器后，同样的指令可能产生前向力加一个不想要的偏航力矩，甚至完全推不动。因此，技能的“动作占用”不能只记在指令坐标 `u` 上，而必须记在**机器人真正能施加到任务上的效果** `e` 上。故障改变的是从指令到效果的映射，不是指令本身。
→ 形式化：故障模式 `f` 给出有效矩阵 `B_f` 与偏置 `b_f`，效果映射 `φ_f(u)=B_f u+b_f`；动作集是效果空间中的像 `A_f=φ_f(U_f)`，技能剖面变成 `α_S^f(e)`。第 54 轮的 `α_S` 只是 `f=0` 的特例。

**灵感 2（从体积兼容到方向可生存：容错是方向性属性）**
直觉：丢了一个执行器，动作空间体积可能只少三分之一，但如果任务恰好需要那个执行器负责的力矩方向，剩下三分之二的体积对这个任务是**零可用**。Jaccard 兼容性问的是“两个技能的动作集合重叠多少”，而容错真正要问的是“任务关键方向还剩多少权限”。一个在关键方向上完全塌缩、但在无关方向上仍有大量体积的组合，会被体积指标误判为可行。
→ 形式化：用任务关键子空间 `T_T` 的正交投影 `P_T`，定义方向权限 `σ_f(T)=λ_min^+(P_T B_f B_f^T P_T)` 与可生存比 `s_f(T)=σ_f(T)/σ_0(T)`；组合的第一性条件从 `compat≥θ_a` 升级为 `survive(S,f,T)`。**反例**：`A_0=[0,1]^3`，故障丢失 `e_3` 后 `A_f=[0,1]^2×{0}`；取 `θ_a=0.5`，体积 `compat=2/3≥θ_a`，但任务 `T=span(e_3)` 时 `s_f=0`——体积兼容放行了一个关键方向完全不可控的组合。

**灵感 3（故障模式是组合图的一等标签，不是事后异常）**
直觉：第 54 轮的组合是一条“技能路径”。但真实执行中，`S_1` 执行到一半发生故障时，正确的后继往往不是标称计划里的 `S_2`，而是一个恢复/降级技能 `S_rec`；而这个后继又取决于故障类型和当前降级模式。把故障当异常分支、等失败了再重规划，等于在故障发生后才开始搜索，时间上已经来不及。
→ 形式化：组合从单路径升级为**故障条件化的 AND-OR 图**：OR 节点选择“技能 × 降级模式”，AND 节点枚举故障分支；一条计划是策略 `π_FT` 而非路径。`F-viable` 要求**所有**故障分支都能在 `τ_max` 内到达目标或安全模式，而不是只要求标称分支可达。

**灵感 4（证书必须按诊断信念条件化，并为未知故障留包络）**
直觉：证书签发时我们并不知道下一秒会不会坏、坏的是哪一个。若证书只写“在标称模型下成立”，故障发生的那一刻它就从 sound 变成 stale，但系统仍可能因为“证书文件还在”而继续复用。正确的做法是让证书显式携带**它覆盖哪些故障、当前诊断信念是否仍落在覆盖域内**；一旦诊断指向域外，证书立即撤销。对于“根本没建模的故障”，不能假装它不存在，而要用一个保守的权限包络把最坏情况包住。
→ 形式化：证书有效域 `F_valid` 与诊断信念 `b` 绑定，`valid(J,b)` 要求 `supp(b)⊆F_valid` 且未知故障质量 `b(⊥)≤ε_⊥`；未建模故障用凸包络 `𝔅=conv{(B_f,b_f)}⊕Δ` 做 min-max 鲁棒分配，要求 `r_𝔅(A_core)≤δ_a`。

**灵感 5（恢复是带暂态的证书，不是终点状态）**
直觉：从“正常行走”切到“单腿安全站立”，终点当然安全；但切换过程中的关节力矩可能瞬间饱和、机身可能先跌一下。只证明终点落在安全集，不能证明切换过程不违反安全约束。容错控制的难点往往不在稳态，而在**故障检测后的暂态**。
→ 形式化：恢复契约 `Rec(f)=(S_rec,τ_safe,P_safe,A_core^rec,ρ_rate,ε_tr)` 同时约束到达时间、成功率、控制变化率与整条暂态轨迹的最大违反；要求 `τ_safe≤τ_max`、`max_t dist(x_t,Safe)≤ε_tr`、`||u_{t+1}-u_t||≤ρ_rate`。

**灵感 6（降级格与任务容忍：不是所有任务都值得 fail-operational）**
直觉：送快递的机器人在故障后“安全停住”是可接受的；载人机器人则必须“带故障继续可控”。容错目标不是单一的“活下去”，而是由任务决定的**最低服务模式**。把降级模式做成格，并让任务声明自己的容忍度，才能避免两种错误：对载人任务过早停机（不可用），对普通任务冒险继续（不安全）。
→ 形式化：降级格 `D={N≻Dg≻H≻E}`，任务容忍 `κ_T∈D`；故障分支可接受当且仅当在恢复前保持 `deg_S(f,e)⪰κ_T`，或在 `τ_max` 内到达 `H/E`。

## 1. 形式化定义（增量：定义 121–130）

**定义 121（故障模式与效果映射）**
故障模式 `f=(κ_f,b_f,σ_f)`：`κ_f∈[0,1]^m` 为执行器有效性（0 失效、1 正常、中间为部分失效），`b_f∈R^n` 为卡死/偏置项，`σ_f` 为传感器故障标志。标称控制效果矩阵 `B_0(q)`，故障后 `B_f(q)=B_0(q)·diag(κ_f)`。同一指令 `u∈U_f` 的效果
```
φ_f(u) = B_f u + b_f,      A_f = φ_f(U_f) ⊆ E
```
其中 `U_f` 固定卡死通道、收紧饱和通道；`E` 为效果空间（力/力矩/速度旋量）。传感器故障不改变 `B_f`，但改变 `α_S` 与 `ρ` 的估计，由定义 126 的信念机制处理。

**定义 122（故障条件化动作空间与技能剖面）**
技能 `S` 在故障 `f` 下的动作剖面 `α_S^f:E→[0,1]`，表示“在 `f` 下执行 `S` 能稳定达到效果 `e`”的校准置信度。覆盖
```
cover_f(S,A_T) ⇔ ∀e∈A_T: α_S^f(e) ≥ θ_cov
```
体积侵蚀 `η_f = 1 - vol(A_f∩A_core)/vol(A_core)` 只作粗指标；下文说明它在方向性任务上会失效。

**定义 123（方向性可生存性）**
任务关键子空间 `T_T⊆E`（由所需力/力矩方向、接触约束方向张成），`P_T` 为正交投影。故障 `f` 的**方向权限矩阵** `M_f=P_T B_f B_f^T P_T`（若考虑输入约束，用局部可控 Gramian `G_f=∫_0^T e^{Aτ}B_fB_f^T e^{A^Tτ}dτ` 的投影）。定义
```
σ_f(T) = λ_min^+(M_f),     s_f(T) = σ_f(T) / max(σ_0(T), ε)
survive(S,f,T) ⇔ σ_f(T) ≥ σ_min(T) ∧ r_f(A_core) ≤ δ_a
```
其中 `r_f` 为控制分配残差。**体积兼容的盲区**：`A_0=[0,1]^3`，故障丢失 `e_3` 方向 → `A_f=[0,1]^2×{0}`；取 `θ_a=0.5`，`compat=2/3≥θ_a`，但 `T=span(e_3)` 时 `s_f=0`。故 `compat` 不能替代 `survive`。

**定义 124（降级格与任务容忍）**
降级格 `D={N≻Dg≻H≻E}`：`N` 标称、`Dg` 降级（仍执行任务但性能下降）、`H` 安全保持（停在安全集）、`E` 紧急停机。任务 `T` 的容忍度 `κ_T∈D` 是可接受的最低模式。技能 `S` 的降级映射 `deg_S:F×E→D`。故障分支可接受当且仅当在恢复完成前 `deg_S(f,e)⪰κ_T`，或已在 `τ_max` 内到达 `H/E`。

**定义 125（容错技能组合图与 F-可行性）**
容错组合图 `G_S^F=(V,E_N,E_F)`：`V⊆S×D` 为技能-模式节点；`E_N` 为标称转移；`E_F` 为故障触发转移 `(S_i,N) --f--> (S_j,d)`，其中 `S_j` 为恢复/降级技能。执行不是单条路径，而是**故障条件化策略** `π_FT:(x,b)→(S,d)`。定义
```
F-viable(π_FT,F,κ_T) ⇔ ∀f∈F:
  执行 π_FT 在 f 下要么以模式 ⪰κ_T 到达目标，
  要么在 τ_max 内到达 H/E 且暂态违反 ≤ ε_tr
```
这把“组合可行”从“存在一条标称路径”升级为“所有故障分支都存在可接受出口”。

**定义 126（诊断信念与证书有效域）**
诊断输出 `b=P(f|o_{1:t})`，定义在 `F∪{⊥}` 上，`⊥` 为未建模故障。证书 `J` 携带 `F_valid⊆F`、签发时信念 `b_issue`、未知故障预算 `ε_⊥`、漂移阈值 `θ_d`。**有效谓词**
```
valid(J,b) ⇔ supp(b)⊆F_valid ∧ b(⊥)≤ε_⊥ ∧ D_KL(b‖b_issue)≤θ_d
```
一旦 `valid` 失效，证书必须撤销并重签发，不得沿用旧证书。这把“故障发生”与“证书失效”显式耦合，避免证书在故障后静默过期。

**定义 127（未知故障鲁棒包络）**
未建模/复合故障用联合凸包络
```
𝔅 = conv{(B_f,b_f): f∈F} ⊕ Δ,   Δ={ (ΔB,δb): ||ΔB||_2≤δ_B, ||δb||_2≤δ_b }
r_𝔅(a) = min_{u∈U} max_{(B,b)∈𝔅} ||B u + b - a||_2
```
若 `r_𝔅(A_core)≤δ_a`，则证书对包络内任意故障成立。工程上可用保守上界 `||B u+b-a||≤||B_c u+b_c-a||+δ_B||u||+δ_b` 化为可解 SOCP；包络越宽，证书越保守，这是“对未知故障付费”的显式代价。

**定义 128（恢复契约与暂态安全）**
恢复契约 `Rec(f)=(S_rec,τ_safe,P_safe,A_core^rec,ρ_rate,ε_tr)`：`S_rec` 为恢复/降级技能，`τ_safe` 为到达安全模式的时长，`P_safe` 为成功率，`A_core^rec⊆A_f` 为恢复期认证动作集，`ρ_rate` 为控制变化率上限，`ε_tr` 为暂态违反上界。要求
```
τ_safe≤τ_max ∧ P_safe≥1-γ_rec
∧ max_{t≤τ_safe} dist(x_t,Safe)≤ε_tr
∧ ||u_{t+1}-u_t||≤ρ_rate
```
恢复不是“终点安全”，而是**整条暂态轨迹安全**。

**定义 129（容错联合证书）**
联合证书 `J^F=(J_perf,J_safe,F_valid,b,s_min,Rec,cov_F,evidence)`：
- `J_perf` 为第 54 轮 `J=(ρ,A_cert,γ_ce,δ_a)`；
- `J_safe` 为安全模式/降级契约；
- `F_valid` 为故障有效域，`b` 为诊断信念；
- `s_min=min_{f∈F_valid}s_f(T)` 为最差方向可生存性；
- `Rec={Rec(f)}` 为分支恢复契约；
- `cov_F` 为故障注入覆盖证据；
- `evidence` 含故障注入轨迹、诊断 ROC、暂态轨迹。

部署谓词
```
deploy(J^F) ⇔ valid(J^F,b) ∧ cov_F≥1-ε_F
              ∧ ∀f∈F_valid: survive(S,f,T) ∧ Rec(f) ok
```

**定义 130（故障覆盖预算）**
`cov(F)=P_{f~D_fault}(f∈F)`，由 FMEA、故障注入与红队采样估计。证书的残余风险至少含 `1-cov(F)`；`cov(F)` 不是常数，而是**可证伪的预算**：每次部署/试验都应更新其下界，未覆盖故障必须计入 `⊥` 并触发定义 127 的保守包络。**没有覆盖证据的容错证书，只是对“已想到的故障”的容错。**

## 2. 关键算法 伪代码

### IP-121 FAM（Fault-conditioned Action Manifold）

```python
def fault_action_set(B0, f, U, sampler, n=4096):
    Bf = B0 @ diag(f.kappa)
    pts = []
    for _ in range(n):
        u = sampler.sample(U, f)          # 卡死通道固定，饱和通道收紧
        e = Bf @ u + f.bias
        pts.append(e)
    return EffectSet(pts).convex_hull()   # 或椭球拟合，保留 feasible 置信度

def fault_profile(skill, A_f, sampler, theta_cov=0.8):
    alpha = {}
    for e in A_f.sample_grid():
        feas, conf = sampler.query(skill, e)
        alpha[e] = conf if feas else 0.0
    return lambda e: alpha.get(e, 0.0)
```

### IP-122 DAS（Directional Authority Survival）

```python
def directional_survival(B0, Bf, P_T, sigma_min, eps=1e-9):
    M0 = P_T @ B0 @ B0.T @ P_T
    Mf = P_T @ Bf @ Bf.T @ P_T
    s0 = lambda_min_psd(M0)
    sf = lambda_min_psd(Mf)
    s_ratio = sf / max(s0, eps)
    return (sf >= sigma_min), s_ratio

def survive(skill, f, T_req, delta_a):
    ok_dir, s = directional_survival(B0, Bf(f), T_req.P_T, T_req.sigma_min)
    ok_alloc = (allocation_residual(skill, f, A_core) <= delta_a)
    return ok_dir and ok_alloc, s
```

### IP-123 FTS（Fault-Tolerant Skill Composition）

```python
def build_ft_graph(skills, F, D, theta_s, tau_max):
    G = ANDORGraph()
    for S in skills:
        for f in F:
            ok, s = survive(S, f, S.T_req, delta_a)
            if ok:
                G.add_or_node((S, deg(S, f)), survive=s)
    for S1, S2 in pairs(skills):
        if nominal_compat(S1, S2):
            G.add_edge((S1, N), (S2, N), kind='nominal')
        for f in F:
            for R in recovery_skills(S1, f):
                if transition_viable(S1, R, f, tau_max):
                    G.add_edge((S1, N), (R, deg(R, f)), kind=f)
    return G

def f_viable(G, F, kappa_T, tau_max):
    for f in F:
        outcomes = and_or_search(G, fault=f, budget=tau_max,
                                 accept=lambda d: d >= kappa_T)
        if not outcomes.safe_or_goal:
            return False
    return True
```

### IP-124 DAC（Diagnosis-Aware Certificate）

```python
def diagnosis_update(b, obs, F):
    b = bayes_update(b, obs, F)
    return b

def cert_valid(J, b, eps_unknown, theta_kl):
    if b.unknown > eps_unknown:
        return False
    if not set(support(b)) <= J.F_valid:
        return False
    if kl_divergence(b, J.b_issue) > theta_kl:
        return False
    return True
```

### IP-125 RRC（Recovery/Reconfiguration Certificate）

```python
def recovery_certify(f, S_rec, simulator, tau_max, eps_tr, rho_rate):
    traj = simulator.rollout(S_rec, fault=f)
    tau_safe = time_to_safe(traj)
    viol = max_violation(traj)
    rate = max_control_rate(traj)
    if tau_safe > tau_max or viol > eps_tr or rate > rho_rate:
        return reject('transient_violation', tau_safe, viol, rate)
    return accept(Rec(S_rec, tau_safe, p_safe(traj), viol, rate))
```

### IP-126 FTIC（Fault-Tolerant Integrated Certificate）

```python
def ft_joint_certificate(plan, J_perf, F, b, cov_F, eps_F, eps_unknown):
    if cov_F < 1 - eps_F or b.unknown > eps_unknown:
        return reject('coverage_or_diagnosis')
    if not cert_valid(J_perf, b, eps_unknown, theta_kl):
        return reject('stale_certificate')
    for f in F:
        ok, s = survive_plan(plan, f)
        if not ok:
            return reject(('survive', f, s))
        if not recovery_ok(plan, f):
            return reject(('recovery', f))
    return accept(JointCert_F(J_perf, F_valid=set(F), b=b,
                              s_min=min_survival(plan, F),
                              Rec=recovery_set(plan, F), cov_F=cov_F))
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| FAM | O(|F|·n·m) 采样 + 凸包/椭球拟合 | O(|F|·n) | 效果集覆盖、卡死偏置建模 |
| DAS | O(|F|·|S|·d^3)（特征分解） | O(|F|·d^2) | 方向权限下界、`P_T` 正确 |
| FTS | O(|S|²·|F|·|D|) 构图；AND-OR 搜索最坏指数 | O(|S|·|F|·|D|) | 故障分支完备、预算可加 |
| DAC | O(|F|·|O|) 信念更新 | O(|F|) | 诊断校准、有效域单调 |
| RRC | O(|F|·|S_rec|·|A|·T) rollout | O(|A|·T) | 暂态上界、恢复率下界 |
| FTIC | O(|S|·|F|·|A| + |F|·T) | O(|S|·|F|·|A|) | 覆盖预算闭合、联合 sound |

**正确性定理（Fault-Tolerant Composition Soundness）**
承接第 53/54 轮 `(A22)–(A28)`，新增：
- **(A29) 故障覆盖**：`P(f*∈F) ≥ 1-ε_F`；
- **(A30) 诊断 sound**：对任一部署证书，`P(f*∈F_valid) ≥ 1-β_d`，且 `P(⊥|f*∈F) ≤ ε_⊥`，检测延迟 `≤τ_d`；
- **(A31) 方向生存下界**：`ŝ_f(T) ≤ s_f(T)`，估计误差 `≤ε_s`；
- **(A32) 恢复契约**：`Rec(f)` 以概率 `≥1-γ_rec` 在 `τ_max` 内到达安全模式，暂态违反 `≤ε_tr`；
- **(A33) 故障剖面校准**：`α_S^f` 为校准下界，控制分配残差 `r_f≤δ_a` 对 `f∈F_valid` 成立。

则在证书有效、覆盖预算成立时，由 union bound：
```
P(success ∨ safe_termination)
 ≥ 1 - ε_F - β_d - ε_⊥ - γ_rec - ε_s
     - Σ_d (1-ρ_min^f(d)) - P(δ_a>Θ_a)
```
关键：**组合前提先验方向可生存**（而非体积兼容），**证书有效域显式覆盖故障**，**恢复暂态也被计入**。四项新增误差中，`ε_F` 通常是主导项，且不能由仿真免费获得。

## 6. 本轮最大风险

**一句话**：FaultGround 的 soundness 最终落在故障集 `F` 的覆盖上——`ε_F` 不是仿真可以免费消掉的常数，而是“我们只对自己想到的故障做了容错”的诚实标价；一旦真实故障落在 `F` 之外，方向可生存性与恢复证书会同时失效，而系统仍可能因为旧证书“看起来有效”继续执行，因此必须把故障覆盖当作一等、可证伪的预算（红队注入 + 未知故障包络 + 在线 `⊥` 检测），宁可保守停机，绝不把“已建模故障下成立”偷换成“所有故障下成立”。

# 第 55 轮产物 · 创新点清单 v32：FaultGround（FAM×DAS×FTS×DAC×RRC×FTIC）

> 承接第 54 轮产物 v31。本轮在动作-协同层 `𝔸` 与鲁棒性层 `𝕃` 之上增加**故障条件化层 `𝔽`**：把“动作空间”从标称指令集升级为**故障模式索引的效果流形**，把“容错控制”从执行层补丁升级为**证书有效域 + 降级契约 + 恢复暂态**。六个算子：
> - **FAM（Fault-conditioned Action Manifold）**：故障模式 → 效果映射 `φ_f` → 动作集 `A_f` 与剖面 `α_S^f`；
> - **DAS（Directional Authority Survival）**：用任务关键方向上的权限 `s_f(T)` 取代体积 Jaccard；
> - **FTS（Fault-Tolerant Skill Composition）**：故障条件化 AND-OR 图与 `F-viable` 策略；
> - **DAC（Diagnosis-Aware Certificate）**：证书有效域 `F_valid` 与诊断信念 `b` 绑定，域外即撤销；
> - **RRC（Recovery/Reconfiguration Certificate）**：恢复契约 `Rec(f)`，约束 `τ_safe`、成功率与暂态违反；
> - **FTIC（Fault-Tolerant Integrated Certificate）**：`J^F=(J_perf,J_safe,F_valid,b,s_min,Rec,cov_F)` 联合签发。
>
> IP 编号：IP-121~IP-126（共 6 个新增），升级 IP-115/116/118/120 以纳入故障模式、方向生存与恢复暂态。

## 0. 一个反例：体积兼容为何不够

第 54 轮的组合条件是 `compat(S_i,S_j)=|A_i∩A_j|/|A_i∪A_j|≥θ_a`。这个指标对故障是盲的，对方向也是盲的。

设标称动作空间 `A_0=[0,1]^3`，某故障 `f` 使第三个效果方向完全失效：
```
A_f = [0,1]^2 × {0}
```
取 `θ_a=0.5`，则
```
compat(A_f,A_0) = vol(A_f∩A_0)/vol(A_0∪A_0) = 2/3 ≥ 0.5
```
体积判据放行。但若任务关键子空间 `T=span(e_3)`，则
```
P_T B_f B_f^T P_T = 0  ⇒  s_f(T)=0
```
即**任务所需的关键方向权限为零**。这不是“性能下降”，而是“该组合在关键方向上不可执行”。因此 FaultGround 把组合的第一性条件改为
```
survive(S,f,T) ⇔ σ_f(T)≥σ_min(T) ∧ r_f(A_core)≤δ_a
```
体积兼容只保留为粗筛，不能作为签发依据。

### IP-121 FAM

```python
def fault_action_set(B0, f, U, sampler, n=4096):
    Bf = B0 @ diag(f.kappa)               # 部分失效/完全失效
    pts = []
    for _ in range(n):
        u = sampler.sample(U, f)          # f 固定卡死通道、收紧饱和通道
        pts.append(Bf @ u + f.bias)
    return EffectSet(pts).convex_hull()   # 或椭球拟合 + 置信度

def fault_profile(skill, A_f, sampler, theta_cov=0.8):
    alpha = {}
    for e in A_f.sample_grid():
        feas, conf = sampler.query(skill, e)
        alpha[e] = conf if feas else 0.0
    return alpha
```

### IP-122 DAS

```python
def directional_survival(B0, Bf, P_T, sigma_min, eps=1e-9):
    M0 = P_T @ B0 @ B0.T @ P_T
    Mf = P_T @ Bf @ Bf.T @ P_T
    s0, sf = lambda_min_psd(M0), lambda_min_psd(Mf)
    return (sf >= sigma_min), sf / max(s0, eps)

def survive(skill, f, T_req, delta_a):
    ok_dir, s = directional_survival(B0, Bf(f), T_req.P_T, T_req.sigma_min)
    ok_alloc = allocation_residual(skill, f, skill.A_core) <= delta_a
    return ok_dir and ok_alloc, s
```

### IP-123 FTS

```python
def build_ft_graph(skills, F, D, delta_a, tau_max):
    G = ANDORGraph()
    for S in skills:
        for f in F:
            ok, s = survive(S, f, S.T_req, delta_a)
            if ok:
                G.add_or_node((S, deg(S, f)), survive=s)
    for S1, S2 in pairs(skills):
        if nominal_compat(S1, S2):
            G.add_edge((S1, N), (S2, N), kind='nominal')
        for f in F:
            for R in recovery_skills(S1, f):
                if transition_viable(S1, R, f, tau_max):
                    G.add_edge((S1, N), (R, deg(R, f)), kind=f)
    return G

def f_viable(G, F, kappa_T, tau_max, eps_tr):
    for f in F:
        res = and_or_search(G, fault=f, budget=tau_max,
                            accept=lambda d: d >= kappa_T,
                            transient_bound=eps_tr)
        if not res.safe_or_goal:
            return False, f
    return True, None
```

def cert_valid(J, b, eps_unknown, theta_kl):

### IP-125 RRC

```python
def recovery_certify(f, S_rec, simulator, tau_max, eps_tr, rho_rate):
    traj = simulator.rollout(S_rec, fault=f)
    tau_safe = time_to_safe(traj)
    viol = max_violation(traj)
    rate = max_control_rate(traj)
    if tau_safe > tau_max or viol > eps_tr or rate > rho_rate:
        return reject('transient_violation', tau_safe, viol, rate)
    return accept(Rec(S_rec, tau_safe, success_rate(traj), viol, rate))
```

### IP-126 FTIC

```python
def ft_joint_certificate(plan, J_perf, F, b, cov_F, eps_F, eps_unknown):
    if cov_F < 1 - eps_F or b.unknown > eps_unknown:
        return reject('coverage_or_diagnosis')
    if not cert_valid(J_perf, b, eps_unknown, theta_kl):
        return reject('stale_certificate')
    for f in F:
        ok, s = survive_plan(plan, f)
        if not ok:
            return reject(('survive', f, s))
        if not recovery_ok(plan, f):
            return reject(('recovery', f))
    return accept(JointCert_F(J_perf, F_valid=set(F), b=b,
                              s_min=min_survival(plan, F),
                              Rec=recovery_set(plan, F), cov_F=cov_F))
```

| E168 证书失效与重签发 | 陈旧复用率、不必要撤销率 | 复用 ≤ 0.5%，误撤销 ≤ 10% |

**故障注入矩阵**：单执行器完全失效、部分失效（`κ∈{0.25,0.5,0.75}`）、卡死（`b_f≠0`）、传感器偏置/漂移、复合故障、域外故障。**消融**：`仅标称` / `+FAM` / `+DAS` / `+DAC` / `+RRC` / `全量`；每个配置至少 5 个随机种子，报告均值与 95% 置信区间。

## 7. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 故障集覆盖不足，域外故障静默穿透 | 高 | 红队注入 + FMEA + 未知故障包络 + 在线 `⊥` 预算 |
| 诊断延迟/漏检使证书故障后仍被复用 | 高 | 证书-信念绑定 + 租约/撤销 + 保守降级 |
| 方向权限估计在接触/饱和下失真 | 高 | 在线辨识 + 保守下界 + 接触期局部 Gramian |
| 恢复动作引发二次故障或暂态越界 | 中高 | 变化率限制 + 暂态 CBF + 影子仿真 |
| 故障注入仿真与真实硬件 gap | 高 | 硬件在环 + 现场故障日志回灌 + 分层校准 |
| 证书频繁撤销导致任务不可用 | 中 | 滞回 + 最小撤销集 + 任务级 `κ_T` |
| 降级格过粗导致模式抖动 | 中 | 模式滞回 + 切换代价 + 迟滞带 |

## 8. 本轮最大风险

**一句话**：FaultGround 的 soundness 最终落在故障集 `F` 的覆盖上——`ε_F` 不是仿真可以免费消掉的常数，而是“我们只对自己想到的故障做了容错”的诚实标价；一旦真实故障落在 `F` 之外，方向可生存性与恢复证书会同时失效，而系统仍可能因为旧证书“看起来有效”继续执行，因此必须把故障覆盖当作一等、可证伪的预算（红队注入 + 未知故障包络 + 在线 `⊥` 检测），宁可保守停机，绝不把“已建模故障下成立”偷换成“所有故障下成立”。
