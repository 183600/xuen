# 想法区 · 第 8 轮：一个掩码，三种用法——把 forcing 从 3.7 µs 打到 0.2 µs，以及 BFS 的 58% 为什么没变成时间

**灵感词**：breadth-first search / derandomization / pruning
**起点**：v2.5「X-DUB/PACE-ΠA-BBX」。held-out 50 例 0.2877 s / 57,236 个 OS 节点；5 个残例 0.02396 s / 4,080 节点；141 合计 0.4359 s。它的收官风险是一句话：

> 这一轮的 1.9× 全部来自「同一棵指数搜索树被剪掉 28.9%、每个节点便宜 1.50×」这两个常数，而不是任何新的可证明下界；一旦分布让 RSI 不触发（或 n>16 出门），剩下的就只有打包的 1.50×，而最坏情况的指数上界一点没动。

我同意「常数」这个判断，但不同意它的隐含结论——常数已经到头了。v2.5 的 HPO 表里其实躺着一个**被误判的赢家**：forcing 少 34.7% 节点，却因为 `ce = 3.70 µs` 被判定为「Python 里输」。这一轮我只问一个问题：

```
ce 到底是剪枝的属性，还是（剪枝 × 表示）这个配对的属性？
```

答案是后者。证据就在 v2.5 自己的代码里。

---

## 一、直觉：EARLIEST 把最有用的东西算出来，然后扔了

v2.5 的 `EARLIEST(AV, r_i, p_i, d_i)` 做的是

```text
x = AV >> r_i
c = x & (x>>1) & … & (x>>(p_i−1))       # 完整可行起点集
s = ctz(c)                                # 只取最早那一个
```

`c` 的第 s 位为 1 当且仅当 `[r_i+s, r_i+s+p_i)` 整段空闲。它把**完整的可行起点集合**算出来了，然后只取 `ctz(c)`，把 `c` 扔了。

可 `c` 里至少还有三样东西：

1. `c = 0` ⇒ RSI，状态死。
2. `c` 只有一个 bit ⇒ 这个 ready 任务**只能**在这个时刻开始，所有「先排别的任务」的兄弟分支都是多余的。
3. `c.bit_count()` ⇒ 这个任务有几个可选起点，MRV 的现成排序键。

第 2 条就是 forcing。v2.5 也做了 forcing，但它是**另写一遍**去判断窗口是否贴死（`t == d_i − p_i`），跑在一个字段更宽、还带 while 循环级联的 `os_prop` 上。于是同一个 `c` 被算了两次，`ce` 被记成 3.70 µs。把 `c` 留下来之后，`ce` 是 **0.22 µs**——差了 17 倍。

```
forcing 不是被 Python 常数打败的，是被「重复计算」打败的。
```

这不是一个实现细节。它改变了 HPO 的结论：同一个 forcing，在 v2.5 的成本模型里是 `0.653 > 0.537`（输），在 v2.6 里是 `0.696 < 0.950`（赢）。**符号翻转完全来自 ce，而不是来自节点数。**

## 二、形式化：M-FRC 与一条交换律

先说清楚 `c`。全资格下状态是 `σ = (R, A, est)`，打包成 `(M, CP, RP)`；`c_σ(u) = |{k : A_k ≤ u}|`，`AV` 是 `c_σ(u) ≥ 1` 的位图。对 ready 的 i：

```text
c_i(s) = 1  ⇔  AV[u]=1 对所有 u∈[r_i+s, r_i+s+p_i)，且 r_i+s ≤ d_i−p_i .
```

**M-FRC（Mask Forcing）**：若存在 `i∈Ready(σ)` 使 `|c_i| = 1`，设唯一可行起点为 t，则把 i 固定在 t，删掉所有其它兄弟分支。

为什么这是对的？我需要一条比「任何完成都必须把 i 放在 t」更干净的路。直觉上，单看一个非时序前缀，`c_σ` 可能低估早期容量（一台机器在 `[A_k, ∞)` 之外其实是空的，却被记成忙）。但这里有一个关键事实：

**交换律**。打包状态只依赖「哪些任务被放在哪些时刻」，不依赖放置顺序。`CP` 是每次放置对 `[t,t+p_i)` 的**逐字段减一**之和，加法可交换；`RP` 是对每个后继取 `max(est_j, t_i+p_i)`，max 可交换。所以「先 i 后 j」与「先 j 后 i」到达**完全相同的 `(CP, RP)`**。

有了交换律，证明就一行：取任一可行完成 S，把它按开始时间排序；在这个时序前缀上 `c_σ` 对 `u ≥ 当前时刻` 是精确的，于是 i 在 S 中的起点必须是 t；由交换律，把 i 提到最前面不改变最终状态。∎

这个证明比我预期的强：**M-FRC 不是启发式，它是 transition relation 的一个 sound restriction。** 而任何 state-local 的 sound restriction 都不会破坏 v2.5 的 NO 序不变性——因为可达状态集只由「归约函数」决定，与兄弟顺序无关。

实测也正是如此：在 50 个 held-out NO 上，`lpt / edd / spt / mrv` 四种顺序的节点数**全部是 39,815**，一位不差。

## 三、成本模型：一次「记账口径」的修正

v2.5 的命题 1 是对的：

```text
值得做 ⇔ N1/N0 < c0/(c0+ce) .
```

错的是代进去的数。把两个内核放在同一批 50 例、同一进程里量：

| 配置 | 节点 | 时间 | µs/节点 | 阈值 c0/(c0+ce) |
|---|---:|---:|---:|---:|
| v2.5 os_pack（RSI，tuple key） | 57,236 | 0.2501 s | 4.37 | — |
| v2.6 os_mask3，RSI，无 forcing | 57,236 | 0.2380 s | 4.16 | — |
| **v2.6 os_mask3，RSI + M-FRC** | **39,815** | **0.1743 s** | **4.38** | **0.950** |

`ce = 4.377 − 4.159 = 0.22 µs`，阈值 0.950，也就是「只要剪掉 5% 就回本」；实际剪掉 30.44%，`N1/N0 = 0.696`。而在 v2.5 的口径下 `ce = 3.70`，阈值 0.537，需要剪掉 46.3%，实际只有 34.7%——**同一个算法，一次输一次赢，差别全在 ce 的记账。**

这里必须澄清一个口径：v2.5 的 37,364 个节点是 `os_prop` 的**宏节点**（它的 while 级联把连续多次强制折叠成一个节点），而本轮的 39,815 是 **lazy 节点**（每强制一次算一个节点）。两者不能直接比大小。能直接比的是**同一个内核加不加 forcing**：57,236 → 39,815。M-FRC 的判据（`|c|=1`，容量单槽）严格包含 v2.5 的判据（窗口贴死 `t = d_i − p_i`），所以它至少不会少强制；宏节点与 lazy 节点的差异只是记账方式。

顺带说一句：内联本身值 1.14×（`os_mask` 0.198 → `os_mask3` 0.174）；若只和 v2.5 的 `os_pack` 比，去掉 forcing 后是 1.05×（0.2501 → 0.2380）。这不是算法，但它说明「每节点成本」这个维度还没被榨干。

## 四、BFS：支配是 order-sensitive 的

「广度优先搜索」这个词让我想了一件很自然的事：把 DFS 换成按 mask 分层的 BFS，每一层把同一 mask 的所有入边状态聚齐，取 Pareto 前沿，再统一展开。这样支配就不受到达顺序影响。

这个想法看上去应该赢。离线统计给了它一个很漂亮的数字：把 DFS 访问过的状态按 mask 分组，逐组取 Pareto 前沿，39,815 → **17,784**，看起来能合并 55.3%。

**这个 55.3% 是个统计陷阱。** 39,815 里有 48.1% 是 memo 命中（同一状态被第二次进入），它们本来就不该被算成「状态」。去重之后真正的不同状态是 **20,653**，Pareto 前沿是 17,784——**只能合并 13.9%**。把 memo 命中当成可合并状态，分母就虚了一倍。

即便如此，BFS 还是值得试，因为它至少能把 20,653 个不同状态压到 16,816（−18.6%）。实测：

| 配置 | 访问状态 | 时间 | µs/状态 | YES 侧（holdout / hard3） |
|---|---:|---:|---:|---:|
| DFS + M-FRC | 39,815 entries / 20,653 不同 | 0.1743 s | 4.38 | 3,983 / 890 |
| DFS + 同 mask 支配 | 36,088 entries | 0.1772 s | 4.91 | — |
| BFS，无支配 | 20,653 | 0.1821 s | 8.82 | 24,770 / 27,039 |
| **BFS + 层内 Pareto** | **16,816** | **0.1732 s** | **10.30** | — |

三件事同时发生：

1. BFS 把状态数从 20,653 压到 16,816（−18.6%），**但时间一点没降**（0.1732 vs 0.1743）。
2. 原因是每次状态访问贵了 2.4 倍：分层字典、`rdy_of`、层内 Pareto 过滤，全都摊到每个状态上。
3. BFS 在 YES 侧是灾难：holdout 24,770 vs 3,983（6.2×），hard3 27,039 vs 890（30.4×）。它必须走到第 n 层才知道成功。

所以 BFS 在本轮的角色不是判决内核，而是**层屏障证书**：一次 BFS 运行本身就给出一个按层组织、带支配边的 DAG，规模 16,816 个状态、最大层宽 375、最多 16 层，检查器只需逐层验证「每个状态的每个孩子都在下一层，或被下一层某个状态支配」。这比 v2.5 的极小核心路线便宜得多——核心提取要 2.5× 判决时间，BFS 只要 1×。

**推论**：v2.5 那句「8 万节点序树就是证书本身」可以退役了。证书不必是树，可以是一张带支配边的分层 DAG；而代价只是一次 BFS。

## 五、derandomization：序是死的，LPT 是唯一活的选择

有了 M-FRC，`Ready` 集上有些节点只剩一个孩子。这时「分支顺序」这个维度还剩多少？

**定理（状态局部归约下的 NO 序不变性）**。固定精确 memo，不用 dominance。若所有剪枝都是 state-local 的（RSI：只看 `c_i`；M-FRC：只看 `|c_i|`），则根不可行时节点数与兄弟顺序无关。

证明骨架和 v2.5 定理 3 一样：可达状态图无环，每个可达父状态都会被完整展开一次，展开时枚举所有未被归约删掉的孩子，所以每条边恰好走一次；顺序只改遍历次序，不改集合。

实测：`lpt / edd / spt / mrv` 在 50 个 NO 上都是 39,815。**序在 NO 上是死维度，而且 M-FRC 没有把它救活。**

YES 上序是活的，但这一次 LPT 赢得干净：

| 顺序 | YES 节点（holdout 50） | 时间 |
|---|---:|---:|
| LPT | **4,000** | 0.0219 s |
| EDD | 4,248 | 0.0241 s |
| MRV | 5,372 | 0.0274 s |
| SPT | 7,140 | 0.0387 s |

这里有一个值得记下的反直觉：**MRV（最受限变量优先）是三个启发式里最像「聪明办法」的那个，却是第二差的。** 原因也简单：NO 上它和 LPT 一模一样（定理保证），YES 上它把「起点选择最少」误当成「最容易成功」，而真正决定 YES 早停的是「长任务先占住容量」——LPT 的活。于是 derandomization 的正确结论不是「找一个更好的随机规则」，而是：

```
在 NO 上删掉这个维度（定理），在 YES 上选 LPT（实测），然后把它写死。
```

## 七、这一轮最像研究的部分

不是 1.42×，是**三个被证伪的直觉**：

1. **「forcing 太贵」是假的。** 贵的是重复计算，不是剪枝。`ce` 是（剪枝 × 表示）的属性。
2. **「55% 的状态可被支配合并」是假的。** 分母里混进了 48% 的 memo 命中；真实可合并率 13.9%。
3. **「BFS 少 58% 状态就该更快」是假的。** 每次状态访问贵 2.4 倍，正好抵消；而 YES 侧还要再慢 6–30 倍。

这三条都指向同一件事：**节点数不是目标函数，甚至不是状态的正确计数。** 下一轮如果再看到「节点少了 X%」，第一件事应该是问：分母里有多少是 memo 命中？

## 八、一句话最大风险

**这一轮的 1.42× 仍然全部是常数：M-FRC 的 30.4% 来自「这批实例里单槽 ready 任务恰好很多」这一分布事实（deep 8 上只有 9.6%），而不是任何新的可证明下界；一旦换到单槽稀少的分布，剩下的就只有内联的 1.05×，而最坏情况的指数上界依旧没动。**

## 0. 版本关系与本轮增量

v2.5 的资产全部保留：

- `ICC`：区间容量证书，只返回有 witness 的 NO；45/45 synth、8/12 hard3、0/50 held-out。
- `CC`：`ICC → OS(10k) → PACE`；每层 sound，UNKNOWN 往下走。
- `OS-RSI`：run-mask 的 `c=0` 判死；打包状态 `(mask, CP, RP)`；增量 ready 位集。
- `CPS`：默认 `probe=0`，只保留开关。
- `PACE`：v2.2 配置的完整后备；`n>16`、异资格、`S>4` 仍由它兜底。

本轮增量只有四件事：

1. **把 run-mask 留下来**：`EARLIEST` 本来就算出了完整的可行起点集合 `c`，v2.5 只取 `ctz(c)`。保留 `c` 之后，RSI（`c=0`）、M-FRC（`|c|=1`）、MRV 键（`|c|`）共用一次计算。
2. **M-FRC（Mask Forcing）**：`|c_i|=1` 时把 i 固定在唯一可行起点，删掉全部兄弟分支。这是 transition relation 的 sound restriction，不是启发式；证明靠一条交换律（§4.1）。
3. **常数重做**：内联 `runmask/apply/key`、单整数 memo key、`c` 的窗口掩码一次算完。每节点 4.37→4.38 µs（几乎不变），但节点 −30.44%。
4. **BFS 层屏障证书（离线，未接主判决）**：按 mask 分层、层内取 Pareto 前沿，得到 16,816 个状态的分层 DAG；用于说明「证书不必是树」。BFS 在 YES 侧慢 6.2–30.4×，**不进入在线级联**。

退化关系：

```text
force=False              → v2.5 OS 的节点数 + 内联常数（57,236 节点，1.05×）
order=lpt/edd/spt/mrv    → NO 节点数完全不变（定理 3）；YES 上 LPT 最好（4,000/4,248/5,372/7,140）
dom=True (DFS)           → 同 mask 支配，36,088 节点 / 0.1772 s（比不加更慢）
dom=True (BFS)           → 16,816 状态 / 0.1732 s（同样不省时间）
n>16 ∨ ¬full ∨ S∉[0,4]  → PACE（与 v2.5 相同）
```

本轮**没有**新增分布相关的门。

## 2. 形式定义

### 2.1 run-mask

给定 `σ` 与 `AV`，对 `i∈Ready(σ)`：

```text
C_σ(i) = { s : r_i ≤ r_i+s ≤ d_i−p_i ,  AV[u]=1 ∀u∈[r_i+s, r_i+s+p_i) } .
```

位向量实现就是 v2.5 的 AND 链：

```text
x = AV >> r_i
c = x & (x>>1) & … & (x>>(p_i−1))
c = c & ((1 << (d_i−p_i−r_i+1)) − 1)
```

**注意**：窗口掩码必须在 AND 链**之后**做。v2.5 的假 NO 就是先截断再找连续 1；本轮沿用修正后的顺序。

`C_σ(i)` 是一个位集，不一定是区间：容量剖面在放置后会掉坑（`c(u)` 在 `[t,t+p)` 上减一），所以 `AV` 可以有洞。

### 2.2 M-FRC

```text
若 ∃ i∈Ready(σ) 使 |C_σ(i)|=1，设 C_σ(i)={t}，则 σ 的唯一后继取为 σ⊕(i,t)。
```

`⊕` 是 §3.2 的 `APPLY`。这条规则把「先排别的任务」的全部兄弟分支删掉。

### 2.3 守卫位布局

为了把「点态 ≥」变成一次大整数减法，每个字段多留一位 guard：

```text
CP 字段 u：位 [cw2·u, cw2·u+cw−1]，值 < 2^cw，最高位（guard）恒 0
GUARD  = Σ_u 2^(cw2·u + cw)
RP 字段 i：位 [rw2·i, rw2·i+rw−1]，值 < 2^rw，guard 恒 0
GUARDR = Σ_i 2^(rw2·i + rw)
```

**引理 2（守卫比较）**。

```text
((A | GUARD) − B) & GUARD = GUARD   ⇔   A_u ≥ B_u 对所有字段 u
```

证明：每个字段 `A_u|1 ≥ 2^cw`，`B_u < 2^cw`，所以字段差 `2^cw + A_u − B_u ∈ [1, 2^(cw+1)−1] > 0`，**永不借位**；其最高位为 1 当且仅当 `A_u ≥ B_u`。∎

`RP` 用同一构造。于是「A 支配 B」=「CP 点态 ≥」∧「RP 点态 ≤」= 两次减法、两次掩码。

### 2.4 状态编码

```text
key = CP | (RP << (cw2·h)) | (M << (cw2·h + rw2·n))
```

单整数 key，避免 3-tuple 的分配与三次哈希。字段宽保证单射。

### 2.5 成本模型（沿用，修正记账）

```text
T0 = N0·c0 ,   T1 = N1·(c0+ce)
值得做 ⇔ N1/N0 < c0/(c0+ce) .
```

关键在于：`ce` 不是剪枝本身的属性，而是**（剪枝 × 状态表示 × 已有计算）**的属性。M-FRC 的 `c` 是 RSI 已经算过的，所以它的 `ce` 只包含「一次 `c&(c−1)` 比较」。

### 2.6 BFS 层屏障

```text
F_0 = {(rem, CP_0, AV_0, RP_0)}
F_{k+1}[M'] = PARETO( ⋃_{(M,·)∈F_k} EXPAND(M,·) 中 mask=M' 的部分 )
NO  ⇔ 某层 F_k = ∅
```

`PARETO` 在同一 mask 内按 §2.3 的支配关系取极大元。证书 = `⋃_k F_k` 加上每条边的父子指针；检查器逐层验证「每个状态的孩子都在下一层，或被下一层某状态支配」。

## 3. 算法

### 3.1 SWEEP：一次扫描，三种用途

```text
SWEEP(RDY, RP, AV):
  cand ← ∅ ; forced ← ⊥
  for i ∈ bits(RDY):
      ri ← (RP >> (rw2·i)) & rmask
      c  ← RUNMASK(AV, ri, p_i, d_i)          # §2.1，保留完整位集
      if c = 0:
          if rsi: return DEAD                 # 用途 1：RSI
          continue
      t ← ri + ctz(c)
      if force and (c & (c−1)) = 0:
          return FORCE(i, t)                  # 用途 2：M-FRC
      cand ← cand ∪ {(i, t, c.bit_count())}   # 用途 3：MRV 键
  return BRANCH(cand)
```

三个用途共用同一次 AND 链。v2.5 的 `earliest` 已经跑了这条链，只是把 `c` 丢了。

### 3.2 APPLY

```text
APPLY(M, CP, AV, RP, PC, RDY, i, t):
  ncp ← CP
  for u in t..t+p_i−1:
      v ← (ncp >> (cw2·u)) & cmask
      ncp ← ncp − (1 << (cw2·u))            # 逐字段减一
      if v = 1: navail ← navail & ~(1<<u)  # 掉到 0 就清 AV
  nrp ← RP & ~(rmask << (rw2·i))
  npc ← PC ; nrdy ← RDY & ~(1<<i)
  for j ∈ succ(i) ∩ M:
      old ← (nrp >> (rw2·j)) & rmask
      new ← max(old, t+p_i)
      if new > old:
          nrp ← nrp + ((new−old) << (rw2·j))
          if new + p_j > d_j: return ⊥      # 期限早死
      v ← ((npc >> (4·j)) & 15) − 1
      npc ← npc − (1<<(4·j))
      if v = 0: nrdy ← nrdy | (1<<j)
  return (M^ (1<<i), ncp, navail, nrp, npc, nrdy)
```

### 3.3 OS-MFX

```text
OS-MFX(σ; B):
  (CP,AV,RP,PC,RDY) ← ENCODE(σ)
  seen ← ∅ ; nodes ← 0
  dfs(M, CP, AV, RP, PC, RDY):
    nodes += 1
    if nodes > B: return UNKNOWN
    if M = 0: return YES
    key ← CP | (RP << (cw2·h)) | (M << (cw2·h+rw2·n))
    if key ∈ seen: return NO
    (cand | forced | DEAD) ← SWEEP(RDY, RP, AV)
    if DEAD: seen.add(key); return NO
    if forced: cand ← [forced]
    sort cand by LPT  (−p_i, d_i, i)        # 序在 NO 上无关（定理 3）
    for (i,t) ∈ cand:
        nxt ← APPLY(…, i, t);  if nxt = ⊥: continue
        sched[i] ← t
        if dfs(nxt): return YES
        del sched[i]
    seen.add(key); return NO
```

### 3.4 级联

```text
MFX(σ,h):
  1  if full(σ):
        v ← ICC(σ,h); if v=NO: return v
  2  if full(σ) ∧ |R|≤16 ∧ 0≤S(σ)≤4:
        v ← OS-MFX(σ; B=10000); if v≠UNKNOWN: return v
  3  return PACE(σ,h)
```

门与 v2.5 完全一致；PACE 配置逐字保留。

### 3.5 BFS-BARRIER（离线，不进主判决）

```text
BFS-BARRIER(σ):
  cur ← {(rem, CP0, AV0, RP0)}
  for k in 0..n−1:
      nxt ← {}
      for (M, cp, av, rp) in cur:
          for (i,t) ∈ SWEEP(rdy(M), rp, av).cand:
              append APPLY(…) to nxt[M ^ (1<<i)]
      for M in nxt: nxt[M] ← PARETO(nxt[M])      # §2.6
      if nxt = ∅: return NO with certificate ⋃_{j≤k} F_j
      cur ← nxt
  return YES iff F_n 含 mask 0
```

BFS 的 `rdy(M)` 只依赖 mask，用 `rdy_cache` 记忆化。

### 3.6 复杂度

设 `r=|Ready|`，`E` 为不同状态数，`N` 为 DFS 进入次数（含 memo 命中），`p_max=max p_i`。

```text
RUNMASK:   O(p_i) 次大整数按位操作（每个数 O(h·cw2/w) 字）
APPLY:     O(p_i + outdeg(i))
SWEEP:     O(r·p_max + Σ outdeg) = O(n·p_max + n²)
节点:      O(n·p_max + n²)
OS-MFX:    O(N·(n·p_max+n²))，N ≤ B；不同状态 E ≤ N
BFS:       O(Σ_f (n·p_max+n²) + Σ_M k_M²)，k_M 为 mask M 的入边状态数
BFS 内存:  O(max_k |F_k|)（本轮最大层宽 375）
级联:      T_ICC + 1_{ICC=UNKNOWN}·B·O(n·p_max+n²) + 1_{OS=UNKNOWN}·T_PACE
```

n≤16、h≤45 的实际数据上，`p_max≤10`，打包后的状态是 2–4 个 Python int；最坏情况仍是指数，MFX 没有打破 NP-hard。

## 4. 定理与证明

### 4.1 引理 0（状态序无关 / 交换律）

**引理 0**。固定 mask 与每个任务的放置时刻，打包状态 `(CP, AV, RP)` 与放置顺序无关。

**证明**。

- `CP`：每次放置对 `[t,t+p_i)` 的每个字段减一；总效果是减去 `Σ_i ONES(t_i,p_i)`，与顺序无关。
- `AV`：`AV[u]=1 ⇔ CP 的字段 u > 0`，由 `CP` 唯一决定。
- `RP`：`r_j = max(est_j, max_{i∈pred(j), i 已放置}(t_i+p_i))`，max 可交换。
- `PC/RDY`：只依赖 mask 与固定优先图。∎

推论：`(CP,RP)` 是 `(mask, 放置时刻多重集)` 的函数，不是路径的函数。

### 4.2 引理 1（时序前缀上的容量精确性）

**定义（时序前缀）**：一条 DFS 路径若其放置的开始时刻非降，称为时序前缀。

**引理 1**。在时序前缀 σ 上，对 `u ≥ t_last`（最后一个放置的开始时刻），`c_σ(u)` 等于 `u` 时刻真正空闲的机器数。

**证明**。把已放置的区间按开始时刻贪心染到 m 台机器上（最大重叠 ≤ m，因为 `CP` 的每个字段非负）。对 `u ≥ t_last`，一台机器若 `A_k > u`，它最后一段区间开始于 `s ≤ t_last ≤ u`、结束于 `A_k > u`，所以在 `u` 忙；若 `A_k ≤ u`，最后一段已结束，所以空闲。故 `c_σ(u)=#{k:A_k≤u}` 正好是空闲数。∎

### 4.3 定理 1（M-FRC 保答案）

**定理 1**。设 σ 可达，`i∈Ready(σ)`，`C_σ(i)={t}`。则 σ 可行 ⇔ `APPLY(σ,i,t)` 可行。

**证明**。

(⇐) 显然。

(⇒) 设 S 是 σ 的一个可行完成。把 S 中所有放置按开始时刻排序，得到时序前缀 σ_S；由引理 1，σ_S 上的 run-mask 是精确的，因此 i 在 S 中的起点 `t_S ∈ C_{σ_S}(i)`。σ 与 σ_S 的放置集合相同（只是顺序不同），由引理 0 二者 `(CP,RP)` 相同，故 `C_σ(i)=C_{σ_S}(i)`，于是 `t_S ∈ C_σ(i)={t}`，即 `t_S=t`。

现在把 i 提到 S 的最前面：由引理 0，先放 i 再放其余任务，最终状态与 S 相同；中间每一步的容量只会比最终容量大（`CP` 单调不增），而 S 中其余任务在最终容量里可行，故在中间容量里也可行。所以 `APPLY(σ,i,t)` 之后仍能完成 S 的其余部分。∎

**注**：这个证明不需要「σ 本身是时序前缀」。非时序 σ 与它的时序重排 `σ_S` 共享同一个 `(CP,RP)`（引理 0），而 `C` 只依赖 `(CP,RP)` 与静态的 `r,d`。这是本轮比 v2.5 的 RSI 证明更干净的地方：v2.5 的引理 1 直接假设 `c_σ` 是精确聚合容量，对非时序状态其实需要额外论证。

### 4.4 定理 2（OS-MFX 的 soundness 与 completeness）

**定理 2**。门内且未撞 B 时：`OS-MFX(σ)=YES` ⇒ 返回的排程可行；`OS-MFX(σ)=NO` ⇒ σ 不可行；σ 可行 ⇒ `OS-MFX(σ)=YES`。

**证明**。

- YES：只有 `M=0` 返回 YES；每次 `APPLY` 保证 `r_i≤t`、`t+p_i≤d_i`、`AV[u]=1 ∀u∈[t,t+p_i)`；`RP` 的 max 传播保证优先序；`d_i=h−q_i` 保证后继链在 h 前完成；全资格下区间图贪心染色到机器。
- NO：搜索树穷尽；RSI 由 v2.5 引理 1（在引理 1 的精确性下成立），M-FRC 由定理 1；memo 只记录已证明失败的状态，引理 0 保证同 key 同未来。
- 可行 ⇒ YES：由 active schedule 定理，存在 active 可行排程 S；沿 S 的时序前缀，RSI 不触发、M-FRC 的固定点与 S 一致（定理 1），故搜索到达 `M=0`。∎

### 4.5 定理 3（状态局部归约下的 NO 序不变性）

**定理 3**。固定精确 memo、不使用 dominance。若所有剪枝都是 state-local 的（只依赖当前 `(mask,CP,RP)`，不依赖兄弟顺序或全局历史），则根不可行时 `OS-MFX` 的进入次数 `N` 与兄弟顺序无关。

**证明**。`mask` 每层严格变小，可达状态图无环。根不可行 ⇒ 每个可达状态都失败；DFS 第一次进入某状态时把它完整展开并加入 memo，之后从别的父状态进入都是命中。每个可达父状态都会被展开一次（失败不会早停），展开时枚举所有未被归约删掉的孩子，所以可达状态图的每条边恰好被调用一次。`ORDER` 只改遍历次序，不改集合。RSI 与 M-FRC 都是 state-local，故归约后的图也不依赖顺序。∎

**实测**：`lpt/edd/spt/mrv` 在 50 个 held-out NO 上均为 **39,815**，逐位相同。

### 4.6 命题 1（成本阈值与符号翻转）

**命题 1**。`T1<T0 ⇔ N1/N0 < c0/(c0+ce)`。

**两次记账**：

```text
v2.5：c0=4.30 µs，ce=3.70 µs  → 阈值 0.537；forcing 的 N1/N0=0.653 → 输
v2.6：c0=4.16 µs，ce=0.22 µs  → 阈值 0.950；forcing 的 N1/N0=0.696 → 赢
```

同一个 forcing，同一个节点比，结论相反。差别只在 `ce`：v2.5 的 3.70 µs 是在 `os_prop`（6-bit 释放字段、while 级联、另算一遍窗口）上量的，把「重新实现」的成本记到了剪枝头上。∎

### 4.7 引理 2（memo 命中对节点指标的污染）

**引理 2**。设 `N` 为 DFS 进入次数，`E` 为不同状态数。则 `N = E + M_hit`，且 `M_hit/E` 可以任意大。

**实测**：v2.5 的 57,236 次进入对应 27,277 个不同状态（命中率 52.3%）；v2.6 的 39,815 次进入对应 20,653 个不同状态（命中率 48.1%）。所以「39,815 → 16,816（BFS）」看起来是 −57.8%，实际是「20,653 → 16,816」= −18.6%。∎

### 4.8 引理 3（BFS 层内 Pareto 的精确性）

**引理 3**。同一 mask `M` 上，若 `CP_A ≥ CP_B` 点态且 `RP_A ≤ RP_B` 点态，则 `B` 的任何完成也是 `A` 的完成；因此删掉 `B` 不影响 `M` 的可行性判定。

**证明**。同一 mask ⇒ 剩余集相同 ⇒ `pc/rdy/d` 相同。把 B 的完成按原时刻放到 A 上：每个任务的释放下界在 A 中不晚于 B（`RP_A≤RP_B`），容量在 A 中不少于 B（`CP_A≥CP_B`），期限是静态的，故全部可行。∎

推论：层内 Pareto 合并是精确的；BFS 的 NO 判定与是否合并无关。

## 5. 实验

### 5.1 设计

**假设**：

- H1（M-FRC 的 ce）：保留 run-mask 后，forcing 的边际成本降到 0.5 µs 以下，从而跨过成本阈值。
- H2（节点）：M-FRC 在 held-out NO 上剪掉 ≥25% 节点，且判决不变。
- H3（序）：state-local 归约下，NO 节点数与顺序无关；YES 上 LPT 最好。

### 5.5 BFS / dominance 的负结果

**离线 Pareto 的统计陷阱**：

| 口径 | 数量 | 「可合并率」 |
|---|---:|---:|
| DFS 进入次数 N | 39,815 | — |
| 不同状态 E（去 memo 命中） | 20,653 | — |
| E 的 Pareto 前沿 | 17,784 | **13.9%** |
| N 直接对 Pareto 前沿 | 17,784 | 55.3%（**错**，分母含 48.1% 命中） |

**在线 DFS 支配**：`front[mask]` 追加式维护，守卫位比较；只命中 467 次（1.2%），节点 36,088，时间 0.1772 s（比不加支配的 0.1743 s 更慢）。原因是支配是 order-sensitive 的：支配者常常后到，而被支配者已经被展开。

**BFS 层屏障**：

- 状态 16,816（相对 E 减少 18.6%），时间 0.1732 s（相对 DFS 0.1743 s，无实质差异）。
- 每次状态访问 10.30 µs，是 DFS 的 2.35×：分层字典、`rdy_of`、层内 Pareto 过滤都摊到状态上。
- 最大层宽 375，最多 16 层，证书总规模 16,816 个状态。
- YES 侧：holdout 24,770 vs 3,983（6.2×），hard3 27,039 vs 890（30.4×），deep 3,047 vs 528（5.8×）。BFS 必须走到第 n 层。

结论：**BFS 是证书工具，不是判决内核。** 它把 v2.5 的「8 万节点序树」换成 16,816 个状态的分层 DAG，代价是一次 BFS 运行（≈1× 判决）；而 v2.5 的极小核心路线要 2.5× 判决时间。

### 5.7 正确性

| 测试 | 规模 | 结果 |
|---|---|---|
| OS-MFX vs 暴力枚举（n=3–6、m≤4、h=3–10） | 2,400 组（1,149 可行，600 组 m=1） | **0 不一致** |

### 5.8 实现陷阱（按代价排序）

1. **SWAR 假零位（borrow）**：第一版用 `(z − ONES_ALL) & ~z & HI` 找归零字段。减法借位会污染相邻字段，把「非零」误判成「零」，于是 `AV` 被错误清空、容量永不耗尽。症状是 held-out 只用 **831 个节点、46 个假 YES**。改用无借位的 `~(((z & LOW)+LOW) | z | LOW) & HI` 后恢复 39,815。**教训**：节点少到不合理时，先怀疑状态更新，不要先庆祝。
2. **字段权重写成 `1<<u`**：`ONES` 表把 CP 字段权重当成 AV 位权，`CP` 减法完全错位，症状同样是几百个节点全 YES。**教训**：CP 与 AV 是两套位宽，任何共享常量都必须显式命名（`cw2`、`BIT`、`BITI`）。
3. **守卫位索引 off-by-one**：`b.bit_length() // cw` 应为 `(b.bit_length()−1) // cw`，否则 `AV` 清错一位。
4. **`rw` 必须包含 `max est`**：只按 h 选释放字段宽会在 `est_i>h` 的不可行状态上溢出。继承 v2.5。
5. **`PC` 4 bits 依赖 n≤16**：这是 `os_gate` 的 `n≤16` 的真正原因。
6. **os_mask vs os_mask3 的 YES 差 17 个节点**：3,983 vs 4,000，来自排序键里是否带 `i` 的细微差异。已记录，不作算法结论。

### 5.9 负结果汇总

1. **BFS 的 58% 状态优势没有变成时间**：16,816 vs 20,653（−18.6%），但每次状态贵 2.35×，净时间为 0。
2. **DFS 同 mask 支配只命中 1.2%**：支配是 order-sensitive 的，后到的支配者救不了已展开的被支配者。
3. **「55.3% 可合并」是 memo 命中造成的分母错觉**，真实可合并率 13.9%。
4. **MRV 是 YES 上的陷阱**：NO 上零收益（定理），YES 上比 LPT 慢 34%。
5. **SWAR 字级并行在 h≤45 上更慢**：`os_mask2` 0.236 s vs `os_mask` 0.196 s。Python 的短循环比大整数并行更快。
6. **forcing 的 while 级联更慢**：`os_mask` 的 closure 版 42,025 个宏节点 / 0.208 s，比 lazy 版 39,815 / 0.196 s 差，因为中间状态没有 memo。
7. **BFS 在 YES 上灾难**：6.2–30.4×，不能进在线级联。
8. **没有形式化验证**：定理 1–3 是纸面证明 + 2,400 组暴力 + 266 例判决一致，没有 Coq/Lean。

## 7. 已知风险

1. **仍是常数，不是渐近**：1.417× 来自 −30.44% 节点和几乎不变的每节点成本；最坏情况仍是指数。
2. **M-FRC 是分布相关的**：held-out −30.4%、hard3 −37.2%、残例 −40.0%、deep 只有 −9.6%。若分布里单槽 ready 任务稀少，增益塌回内联的 1.05×。
3. **`ce` 依赖实现**：0.22 µs 是 Python 内联版的数；换 C 会变，但方向不变（`c` 仍然只算一次）。
4. **n≤16 的门**：`PC` 4 bits 与 `os_gate` 都依赖 n≤16；n>16 回 PACE。
5. **守卫位布局的字段上界**：要求 `c(u)<2^cw`、`r_i<2^rw`，由构造保证；任何字段宽改动都要重验。
6. **BFS 只是离线证书**：YES 侧 6.2–30.4× 退化；层屏障检查器尚未独立实现（只测了规模与生成成本）。
7. **BFS 的 Pareto 合并改变可达集**：16,816 是「先合并再展开」后的状态数，不是离线前沿的 17,784；两者不可直接比。
8. **DFS 支配未启用**：36,088 节点 / 0.1772 s，比不加更慢；`front[mask]` 是追加式的，内存随状态数增长。
9. **`os_mask3` 的 YES 节点比 `os_mask` 多 17 个**：排序键差异，未追到根因。
10. **memo 无上限**：held-out 单例最大 20,653 个 key；n=16 的更坏实例可能指数增长，没有内存上限。
11. **时间测量单机**：4 vCPU 单线程，Python 3.12，±3%；节点数不能直接当时间（引理 2）。
12. **公共期限**：各自期限 `d_i` 的路径未实现。
13. **没有形式化验证**：定理 1–3 是纸面 + 2,400 组暴力 + 266 例判决一致。
14. **`pmax=16,tau=4,B=10k` 未调**：门本身仍可能是下一轮的收益点。
15. **M-FRC 的证明依赖引理 0 的「max 可交换」**：若未来加入机器相关的 setup time 或非全资格，交换律失效，M-FRC 不再 sound。

---

## 8. 一句话最大风险

**这一轮的 1.42× 仍然全部是常数：M-FRC 的 30.4% 来自「这批实例里单槽 ready 任务恰好很多」这一分布事实（deep 8 上只有 9.6%），而不是任何新的可证明下界；一旦换到单槽稀少的分布，剩下的就只有内联的 1.05×，而最坏情况的指数上界依旧没动。**
