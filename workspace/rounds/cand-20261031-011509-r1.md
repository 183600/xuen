# 第 13 轮 · UIBVS-MVP：把最后 3 厘米交给「无标定腕部图像伺服」，用最小闭环先证明 +10pp

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是灵感循环第 1 轮（承接第 10–12 轮），三个词是「最小可行产品」「具身智能」「闭环控制」。本轮不推倒 FACT-VLA / GEO-RESIDUAL / CHUNK-SERVO，而是把 CHUNK-SERVO 从「30 步规划 + 5 步伺服 + 演示检索 + 虚实标定」的大工程，压缩成一个一周可验证的 MVP：**一个任务、一个控制器、一个指标**。核心判断：**VLA 是规划器，不是执行器；最后 3 厘米应由无标定、无学习权重的腕部图像伺服闭环完成。**

## 0. 先纠正前提：29.7% 是 preview，不是实时榜首

截至 2026-10-31，官网首页/榜单仍显示 8 个模型：MolmoAct 29.7%、WALLOSS 28.5%、DreamZero 27.9%、spirit 25.9%、DM 23.5%、PI 22.8%、GigaBrain 22.6%、gr00t 20.5%。但这不是实时榜单：

1. `leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`；
2. 8 模型 ×32 任务 = 256 条 runs，成功率出现 27.29%、27.85%、37.01% 等非 10% 整数倍；而规则是每任务 10 次独立运行，真实成功率只能是 0/10、1/10、…、10/10；
3. 详情页 32 个任务的视频全部写着「测试视频占位，后续可替换为真实视频文件」；
4. 页面底部同时写着「即将发布 / Coming Soon」。

结论：把 29.7% 当作赛事方的难度/预览信号可以；把它当真实 SOTA、任务难度表、失败分布，不可以。真正的机会不是去猜这 8 个 preview 分数，而是**在真实榜单开放前，先把一个能在真机上跑通的闭环 MVP 做出来**。这也直接决定了本轮的策略：不做「更大的 VLA」，做「更小的闭环」。

## 1. 本轮新核实的事实（只列会改变方案的）

### 1.1 规则与 API（A）

- 32 项桌面任务；每任务 10 次独立运行；5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰）各 2 次；单次上限 180 s。
- 所有任务须基于**同一模型**；模型类型不限；只设通才模型赛道；另有**不计分的单任务测试通道**。
- 排名：32 任务总平均成功率 → 总平均步骤分 → 更早提交。
- 评测跨 N 台机器人；提交须从 8765 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态隔离。
- 观测：4 路 RGB 480×640（左右头、左右腕）、双臂关节、EE 位姿、夹爪、下身体、语言；**没有 depth、camera_info、force/torque、tactile**。
- `action_chunk_size` 固定；chunk 内按顺序执行，直到 evaluator 再次调用 `get_action`；chunk 内没有新观测，也没有打断机制。
- 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分。

### 1.2 数据（A）

- HF 合集 32 个 G1_Dex1 数据集；官方页面写 32,000 demos / 169 h；逐数据集合计约 **33,276 episodes / 18,282,246 frames / 169.28 h**，30 fps。
- 四路视频：`head_stereo_left/right`、`wrist_left/right`，480×640。
- 头部双目有完整内参、畸变、R/T、基线 **58.2526 mm**、`rectified: true`。
- **腕部相机没有内参矩阵**（`camera_params` 只有 `color/ir1/ir2`）。这是本轮 MVP 的直接约束。
- 数据里还有 `state_d435`、`waist_state_joint`、EE 位姿、夹爪、下身体；线上 API 没有 `state_d435`，但有 `lower_body`，头相机外参能否在线恢复需要实测。

### 1.3 官方基座（A）

- **UnifoLM-WLA-1.0**：6B 参数，约 2,500 h 真机数据，64 个任务；默认 `chunk_size=30`、`target_fps=30`，覆盖约 `[0, 29/30]` 秒；4 步扩散去噪；微调冻结 VLM，只训 DiT action head + robot-state projector，单张 24GB GPU 可跑；Base 权重与微调代码 2026-09-28 开源。
- 统一动作 **54 维**、状态 **60 维**；挑战赛 API 的 `ee` 模式是 2×6 EE + 2×1 gripper + 7 pivot = 21 维，需要 adapter。
- 官方 WLA 是否已覆盖挑战赛 32 任务、`pivot` 语义是否一致，必须在单任务通道实测。

### 1.4 腕部相机在最后 3 厘米能看到目标（B，本轮新增一手证据）

2026-10-31 从 HF `G1_Dex1_HangCup` 的 `wrist_left` 视频（`videos/observation.images.wrist_left/chunk-000/file-000.mp4`）抽取 t=4 s、t=6 s 帧：

- t=4 s：腕部画面同时看到绿色杯子、木质杯架立柱、左侧背景杂物；
- t=6 s：杯子已接近杯架，杯口与立柱同时在画面中心，夹爪两指在画面底部。

这说明 **HangCup 的最后 3 厘米不是「盲插」**：腕部相机有可跟踪的目标（立柱/杯口），且不需要深度。这是本轮把 UIBVS 作为第一 MVP 的直接依据。其他任务（插网线、叠碗、拉拉链）是否同样可见，必须先过 G0，不能假设。

### 1.5 头部方案与近期工作（A+B）

榜单头部的 8 个名字对应真实的公开模型家族：MolmoAct2（Ai2，action reasoning + adaptive depth）、WALL-OSS-0.5（X Square，4B VLA）、DreamZero（14B video-diffusion world-action）、Spirit-v1.5、DM0、π0.5、GigaBrain-0、GR00T N1.5。它们的共同点不是「语义不够」，而是：

- 都输出 action chunk，chunk 内开环执行；
- 模型越大，chunk 越长，越不反应；
- 世界模型解决「想象未来」，不解决「现在偏了 2 mm」；
- 单模型规则让「再加一个学习残差」变得危险。

2026 年的近期工作已经把「闭环」做成热词：VLA-Corrector（detect-and-correct、自适应 horizon、无需重训主干）、A2C2（轻量 correction head、每步修正）、VeriVLA / VeriSpace / Gated GeoBoN（测试时验证/选块）、PACT-VLA（用 pre-commit 观测选块）、VLA-Feedback（把最后一步去噪当反馈接口）、FIRe（力残差，但需要力传感器）。它们证明了方向，但也暴露了一个空位：

> **大多数方法要么训练一个 correction head / verifier，要么需要力/触觉，要么需要标定好的相机；而挑战赛恰好没有力/触觉、腕部相机没有内参、单模型规则又不欢迎第二个学习模型。**

这个空位就是本轮 MVP 的定位：**training-free、calibration-free、force-free 的确定性闭环控制器**。

## 2. 诊断：为什么「最小」的闭环不是「更小的 VLA」

把一次接触失败拆开：

```text
t0: 观测 → VLA 推理 (100-300ms) → 返回 30 步 chunk
t0+0.1s: evaluator 开始执行 chunk
t0+0.1s … t0+1.1s: 机器人开环执行 30 步
        ↑ 接触/滑移/人移动物体都发生在这一段
t0+1.1s: 才看到下一帧 → 已经晚了
```

三个「1 秒」：规划 1 秒、推理/网络 0.1–0.3 秒、恢复 1 秒。视觉伺服的价值不是「更准的感知」，而是把第 3 个「1 秒」降到最后 3 厘米内的 **167 ms 执行块**（5 步 @30 Hz；含 RTT 端到端约 200–320 ms）。

但 CHUNK-SERVO 的第 12 轮版本有一个问题：它同时要求 30 步规划、5 步伺服、演示检索、数字孪生标定、32 任务组合——这是一个 9–10 周的大工程，不是一个 MVP。**MVP 的原则是：先证明最核心的因果，再扩展。** 本轮把因果链压缩成：

> 如果最后 3 厘米的失败主要是**横向对齐**，那么一个只看腕部图像、不需要标定、不需要训练的 2D 图像伺服，就应该在 HangCup 上把成功率提高 ≥10pp。

如果这个命题不成立，后面的 30 步规划、演示检索、数字孪生都不值得做。如果成立，再按任务族复制。

## 3. 方案：UIBVS-MVP

### 3.1 一句话

**VLA 负责「接近 + 下压」的前馈，UIBVS 负责「最后 3 厘米」的 2D 横向闭环；不标定相机、不训练第二个模型、不用力/触觉。**

### 3.2 为什么是 UIBVS，不是 PBVS / 学习残差

| 方案 | 需要什么 | 在本赛事的致命问题 |
|---|---|---|
| PBVS（头双目 + 3D 目标位姿） | 相机内参/外参、目标 3D 模型/检测 | 腕部无内参；头相机外参在线恢复未验证；透明/反光目标深度差 |
| 学习残差（A2C2/FIRe 类） | 第二个学习模型/修正头 | 单模型规则风险；需要训练数据/算力；FIRe 还要力传感器 |
| 学习 verifier（VeriVLA/VeriSpace） | 第二个 VLM/世界模型 | 单模型风险；326 ms 级额外延迟；需要 GPU |
| **UIBVS（本轮）** | **腕部图像 + EE 位姿 + 机器人自身运动** | **目标必须可见；雅可比要在线估计；延迟下增益要降档** |

UIBVS 的核心不是「视觉」，而是「用身体学映射」：它不需要知道相机焦距、安装角、目标深度；它只需要观察「我动了一下，目标在图像里动了多少」，在线估计图像雅可比。**这正是「具身智能」在控制层的含义：身体本身就是传感器。**

### 3.3 控制对象：只做 2D 横向，不做 6D

MVP 不试图用视觉控制全部 6 个自由度。它只控制 **tool frame 的 x/y 两个横向自由度**；z（接近/插入/下压）由 VLA 的前馈计划负责，gripper 由 VLA 控制，pivot 先保持零/跟随 VLA。理由：

- 最后 3 厘米的失败主要是横向错位，不是深度错位；
- 2×2 雅可比只需要几对视觉-运动数据，容易在线估计；
- 避免深度估计、相机标定、6D 位姿网络；
- 与 API 的 `ee` 绝对位姿动作天然兼容：在 VLA 的 5 步轨迹上叠加一个横向偏移即可。

### 3.4 MVP 阶梯（M0–M6）

| 阶段 | 做什么 | 成本 | 通过标准 | 失败就停 |
|---|---|---|---|---|
| **M0 基线** | 注册/ token / N 端口；官方 WLA + API adapter；单任务通道跑 HangCup | 2–3 天 | 握手、token、动作形状、reset 全过；有成功率/延迟日志 | 接口不通，先修接口 |
| **M1 chunk governor** | 同一 VLA，扫 `T_a=1/5/8/30`；测 RTT、p99、成功率 | 2 天 | 找到 `T_a` 的成功率/延迟折中；p99 ≤150 ms | 全部 timeout/抖动，回退大 chunk |
| **M2 离线 UIBVS** | HangCup 成功演示 + 注入图像偏移；2×2 Broyden；调增益/死区/饱和 | 3–4 天 | 注入误差收敛 ≥80%；无振荡 | 特征跟踪不稳，换特征/换任务 |
| **M3 真机 HangCup** | 单任务通道 A/B：servo off/on；5 次配对 | 1 周 | +10pp；p99 ≤150 ms；无回归 | 不提交 servo 版本 |
| **M4 同族扩展** | StackBowls / PaperCupStacking；PlugInEthernet / PlugCharger | 1–2 周 | 3 个任务中 ≥2 个 +10pp | 只保留有效任务 |
| **M5 恢复** | stuck/slip 检测 + 重试；human 轴 | 1 周 | 检测 ≤200 ms；恢复 ≥50% | 只做离线分析 |
| **M6 全量** | 32×10 干跑；只保留有效族 | 1 周 | 端口隔离、内存不涨、p99 稳定 | 回退基线 |

**M3 就是 MVP**：一个任务、一个控制器、一个指标。M4 之后才是产品化。

### 3.5 为什么先做 HangCup

- 单任务平均时长最短（6.2 s），迭代快；
- 腕部相机已确认能看到杯架立柱与杯口（本轮抽帧）；
- 失败是清晰的横向/高度对齐问题，适合 2D 伺服；
- 1,043 条成功演示，离线回放样本足够；
- 任务属于「最后 3 厘米」A 档，成功后可直接复制到 StackBowls / PaperCupStacking。

### 3.6 为什么不是一上来做插网线

PlugInEthernet / PlugCharger 的孔更小、插头/线缆有变形、腕部相机可能被插头遮挡；它更适合作为 **M4 的第二个族**，而不是 MVP 的第一题。先把「可见目标 + 刚体对齐」的 HangCup 打穿，再攻插入。

## 4. 创新点清单（持续迭代，不推倒重来）

> 评分：P0 现在做；P1 通过 M3 后做；P2 有余力再做；P3 后置/观察。  
> 证据等级：A=官方/数据直接核实；B=我们在公开数据/网页上的分析；C=设计假设，需实验。

### I1 · UIBVS-MVP（新，P0）

- **动机**：腕部相机无内参、API 无深度/力、单模型规则禁止第二个学习模型；最后 3 厘米需要闭环。
- **与现有方案差异**：不标定、不训练、不用第二个模型；用机器人自身运动在线估计 2×2 图像雅可比；与 VLA-Corrector / A2C2 / VeriVLA / PACT 的训练型/验证器型路线不同。
- **技术可行性**：经典 uncalibrated visual servoing 有 20+ 年文献（Broyden/RLS/robust M-estimation）；HangCup 腕部帧已验证目标可见；2×2 雅可比只需几对数据；CPU 实时。
- **新颖性边界**：UIBVS 本身不是新算法（20+ 年）；本方案的新颖性是「在无腕部内参、无深度、无力/触觉、单模型约束下，把 2×2 无标定图像伺服作为 VLA 的最小外挂闭环」，以及「chunk governor + 族级复制 + 可证伪的 MVP 证据链」这套系统组合。不要把它包装成新视觉伺服理论；它的价值是工程收敛和可复现的 +10pp。
- **所需资源**：1 张 GPU 跑 WLA；1 台机器跑 PolicyService；HangCup 数据；单任务通道；1 人周。
- **落地步骤**：M0 → M1 → M2 → M3；M3 不过就不扩展。
- **风险**：目标遮挡/弱纹理；雅可比初值/稳定性；RTT；VLA 与伺服冲突；单模型合规解释。

### I2 · FAMILY-PRIMITIVES（新，P1）

- **动机**：32 个任务不能逐个做；插入、悬挂、叠放、开启共享几何与接触力学。
- **与现有方案差异**：不是 32 个任务策略，而是 4 个族级「最后 3 厘米」原语；UIBVS 提供通用横向修正，族原语提供轴向动作（下压/螺旋/旋转）。
- **技术可行性**：插入（对准 + 螺旋搜索）、悬挂（对准 + 下压）、叠放（对准 + 下压）、开启（对准 + 旋转）都是经典 primitives；API 的 EE 绝对位姿足够。
- **所需资源**：每族 3–5 个任务的数据；单任务通道；1–2 人周。
- **落地步骤**：先悬挂/叠放族（HangCup/StackBowls/PaperCupStacking），再插入族（PlugInEthernet/PlugCharger/ArrangeTestTubes），再开启族（OpenPillBottle/ZipUp/Unlock）。
- **风险**：族内差异大；无力/触觉；透明/反光；步骤分可能因额外修正而变差。

### I3 · JACOBIAN-CHUNK-SELECT（新，P2）

- **动机**：生成式 VLA 的多个 chunk 质量不同；学习 verifier 是第二个模型；几何 verifier 需要 3D/标定。
- **与现有方案差异**：用 UIBVS 的局部雅可比预测每个候选 chunk 的**图像特征终点**，选误差最小的；不需要第二个模型、不需要深度。
- **技术可行性**：WLA 的 action head 可多采样；VLM 特征可复用；2×2 雅可比预测很便宜；CPU 可算。
- **所需资源**：1 张 GPU；WLA 代码；离线数据；1 人周。
- **落地步骤**：HangCup 上采样 K=4/8；离线评估选块与真实终点的一致性；真机 A/B。
- **风险**：雅可比局部有效；多采样增加延迟；选块过拟合到图像特征；与 UIBVS 增益耦合。

### I4 · CHUNK-GOVERNOR（深化，P0）

- **动机**：`action_chunk_size` 固定，但反馈周期 ≈ `T_a/f_c + RTT`；默认 30 步 = 1 秒开环。
- **与现有方案差异**：把 chunk size 当**控制超参数**，用单任务通道测 1/5/8/30；不是拍脑袋。
- **技术可行性**：API 支持任意 `T_a`；WLA 可输出 30 步，取前 `T_a` 步；PolicyService 可配置。
- **所需资源**：极少；1–2 天。
- **落地步骤**：同一 VLA、同一任务，扫 `T_a`；测成功率/p99/timeout；选最佳。
- **风险**：`T_a` 太小导致网络抖动/推理跟不上；evaluator 的控制频率未知；不同任务最佳 `T_a` 不同。

### I5 · FLIGHT-RECORDER（新，P0）

- **动机**：公开榜单是 preview，没有真实失败分布；单任务通道是唯一真机数据源。
- **与现有方案差异**：在 PolicyService 里记录每步 obs/action/latency/feature；离线复盘；不是只报成功率。
- **技术可行性**：Python 日志；图像压缩；磁盘足够；不违反 API。
- **所需资源**：1 人天；存储 10–50 GB。
- **落地步骤**：基线跑 1 个任务；记录；人工标注失败阶段；更新任务组合。
- **风险**：图像日志太大；评测端可能不允许额外 I/O（不影响动作）；数据合规。

### I6 · GEO-RESIDUAL RECOVERY（保留，P2）

- **动机**：人为干扰占 20%；检测场景被改，停-重定位-重规划。
- **与现有方案差异**：动作条件化残差，不需要识别人类；与 UIBVS 的门控结合。
- **技术可行性**：已有第 11 轮设计；需要深度/几何；CPU。
- **所需资源**：1 人周；单任务通道。
- **落地步骤**：离线合成编辑；真机 human 轴 A/B。
- **风险**：深度不可用；透明/反光；误报。

### I7 · FACT-VLA（降级，P3）

- **动机**：相位分割有助于门控。
- **与现有方案差异**：原为学习型相位分类；现在降级为**规则/无监督相位检测**，避免第二个模型。
- **技术可行性**：用夹爪开合、EE 速度、目标距离做规则；不需要训练。
- **所需资源**：1 人周。
- **落地步骤**：离线验证相位边界；线上门控 UIBVS。
- **风险**：规则不鲁棒；任务差异大。

### I8 · WLA ACTION-HEAD FINE-TUNE（后置，P3）

- **动机**：官方 WLA 未针对 32 任务微调；action head 微调便宜。
- **与现有方案差异**：只训 action head + state projector，冻结 VLM；24GB。
- **技术可行性**：官方代码；数据；1–2 GPU 周。
- **所需资源**：1 张 24GB GPU；2–3 周。
- **落地步骤**：先 baseline；再微调；单任务通道 A/B。
- **风险**：过拟合；数据质量；可能不如闭环增益大。

### 本轮剪枝（不做/后置）

- 从零训 VLA/World Model：官方 WLA 已开源，算力不划算。
- 完整 sim-to-real 策略训练：sim gap；数字孪生只做控制器风洞。
- 32 个任务各训一个策略：规则禁止且不泛化。
- 30 Hz 广域网伺服：RTT 不允许；用 5 步 chunk / 双频。
- 第二个学习模型/残差网络：单模型风险；用确定性控制器。
- 6D 物体位姿网络：透明/变形不可靠；用 2D 特征 + 相对目标。
- 力/触觉闭环：API 没有。
- 把 preview 榜单当真实难度表：已证伪。
- 纯世界模型路线：推理重，不解决最后 3 厘米。

## 5. 竞赛策略：先锁一个族，再谈 32 任务

- 32 个任务等权；一个任务 +10pp 只值 +0.31pp 全局。要拿到 +3–5pp，必须在 **10–16 个任务**上同时生效。所以 MVP 的单位不是「任务」，而是「任务族」。
- 任务族先验：
  - **悬挂/叠放**（约 6 个）：HangCup、StackBowls、PaperCupStacking、StackCups、ArrangePlates、StoreRacket。
  - **插入**（约 6 个）：DisconnectEthernet、PlugCharger、PlugInEthernet、ArrangeTestTubes、Unlock、SyringeWaterTransfer。
  - **开启/闭合**（约 5 个）：OpenPillBottle、ToolboxStorage、ZipUp、PackBag、PlacePhotoFrame。
  - **抓放/分类/变形**（其余）：主要交给 VLA，UIBVS 不强上。
- 算术：6 个悬挂/叠放 + 6 个插入 + 5 个开启，共 17 个任务；若各 +10pp，全局 `17/32×10≈+5.3pp`；若各 +15pp，`+8.0pp`；human 轴 +10pp 再 `+2pp`。保守目标 +3–5pp，乐观 +7–8pp。**这些是设计目标，不是承诺；M3 不过就不提交。**
- 单任务通道协议：HangCup（MVP）→ StackBowls（同族）→ PlugInEthernet（插入族）→ ZipUp（开启族，防回归）。每个任务先 5 次 A/B，配对设计；记录成功率、步骤分、p99、目标可见率、修正幅值。
- 提交节奏：先确认是否允许多次计分提交。若允许，先交安全基线锁「更早提交」tie-break；若不允许，M3/M4 通过后再交。不要用正式 320 trials 做未验证的 A/B。
- 部署：N 未知；按 N=3 设计，每端口独立 `reset()`/UIBVS 状态；VLA 可共享；保持 p99 稳定，避免动作异常。

## 6. 一句话押注

**把 VLA 降级为前馈规划器，把腕部相机升级为闭环传感器：用无标定图像雅可比伺服（UIBVS）在最后 3 厘米做 2D 横向修正，先在 HangCup 上证明 +10pp，再按悬挂/叠放/插入/开启四个任务族复制。**

# 第 13 轮产物 · UIBVS-MVP 技术报告

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「UIBVS-MVP」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是把 CHUNK-SERVO 压缩成一个一周可验证的最小闭环。

## 0. 结论与边界

### 0.1 一句话结论

公开榜单的 29.7% 是 preview（脚本生成 + 占位视频 + 非 10% 整数倍成功率），不是实时 SOTA；真实瓶颈不是「更大的 VLA」，而是 action chunk 内 1 秒开环执行与最后 3 厘米接触精度。最小可行产品不是再训一个模型，而是一个**无标定、无学习权重、无力/触觉的 2D 腕部图像伺服**：VLA 负责接近/下压的前馈，UIBVS 负责最后 3 厘米的横向闭环；先用 HangCup 一个任务证明 +10pp，再按任务族复制。

| 等级 | 含义 | 本报告中的例子 |

| A | 官方文档、提交模板、数据集元数据、排行榜 JSON 直接核实 | 规则、API、33,276 eps、WLA `chunk_size=30`、榜单 JSON |

- 不做完整 sim-to-real 策略训练；数字孪生只做控制器风洞（可选）。

### 1.2 提交 API（A）

提交模板 README（2026-10-31 复核，版本 2，最后 commit 2026-08-21）给出：

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640** |
| 本体 | 双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str` |
| 动作空间 | `control_space` 仅 `"joint"` 或 `"ee"`，二者互斥 |
| 共享动作 | `action.left_gripper [1]`、`action.right_gripper [1]`、`action.pivot [7]` |
| EE 动作 | `action.left/right_ee_pose_gripper_base [6]`（绝对目标位姿，xyz+rpy，base 系） |
| chunk | `action_chunk_size` ≥1，固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action` |
| token | `metadata.token` 握手校验；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile** |
| 监控 | 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分 |

**关键推论**：`action_chunk_size=30`、控制频率 30 Hz 时，一次 `get_action` 之后有 **1 秒开环执行**；chunk 内没有新观测，也没有打断机制。控制频率未在 README 中写死；本报告默认 30 Hz，必须在单任务通道实测。

取证分析（B）：

1. `leaderboard_data.json` 的 `generated_from` 是 `"gen_leaderboard.py"`；`Published Time: Thu, 08 Oct 2026 15:35:03 GMT`。
2. 对 8 个模型 ×32 任务做 `step_score ~ success_rate` 回归，**R² > 0.999999，最大残差 <0.006**；每个模型的斜率不同，形式是 `step ≈ k_model × success`。这不是实测步骤分，是脚本生成的线性缩放。
3. 详情页 `details.html?model=MolmoAct2&user=DexHacker` 的 32 个任务视频全部是「测试视频占位，后续可替换为真实视频文件」。
4. 8 个模型的 32 维任务成功率两两相关，**平均 off-diagonal 相关系数约 0.098**；如果任务难度是真实的，不同模型的任务级成功率应该正相关。
5. 每任务只有 10 次 trial，但成功率出现 27.29%、27.85%、37.01%、38.43% 等非 10% 整数倍；真实 10 次 trial 只能是 0/10、1/10、…、10/10。
6. 页面底部同时显示「即将发布 / Coming Soon」。

**结论**：29.7% 可以作为「赛事方预览上限/难度信号」；不能作为 SOTA、任务难度表或失败分布。本轮不从榜单任务排名挖创新点，只从公开模型家族的技术路线和官方数据/规则里挖。

### 1.7 头部方案的做法与瓶颈（A+B）

| 模型家族 | 公开路线 | 优势 | 与本轮相关的瓶颈 |
|---|---|---|---|
| **MolmoAct2** | Ai2 的 action reasoning model；Molmo 2-ER + 专用 action expert + adaptive depth reasoning；大规模双臂数据；强调 3D 空间推理、推理加速、无 per-task 微调 | 3D/空间语义强；推理快；双臂 | 仍然是开环 chunk；最后插入/挂/拉链的接触精度与恢复 |
| **WALL-OSS-0.5** | X Square 的 4B VLA（3B VLM + action expert）；公开材料称 15 个真机任务上 60.5% average task progress | 预训练直接可用；progress 高 | progress ≠ success；最后一步失败就 0 分；4B 的实时性 |
| **DreamZero** | 14B Wan2.1 video-diffusion world-action model；世界模型预测未来视频再出动作 | 长程预测/规划 | 14B 推理重；世界模型不直接解决接触力/毫米级对齐；1 秒 chunk 更危险 |
| **π0.5** | Physical Intelligence 的开放世界泛化 VLA | 语义/新场景泛化 | 接触密集任务的精度；远程部署延迟 |
| **GigaBrain-0** | 世界模型生成数据 + VLA；用世界模型降真机数据依赖 | 数据效率/泛化 | 生成数据的物理保真度；最后 3 厘米 |
| **GR00T N1.5** | NVIDIA 通用人形 VLA | 生态/embodiment | 任务特定精度；数据覆盖 |

共同点：

- 都是 action chunk 开环执行；chunk 内不看新图。
- 模型越大，chunk 越长，越不反应；长 chunk 与接触精度直接冲突。
- 世界模型解决「想象未来」，不解决「现在偏了 2 mm」。
- 单模型规则让「再加一个学习残差」危险；但「确定性视觉伺服」不是模型，是控制器。

### 1.8 近期工作与空位（A）

2026 年「闭环 VLA」已经是活跃方向：

| 工作 | 做法 | 与 UIBVS-MVP 的差异 |
|---|---|---|
| VLA-Corrector（arXiv 2607.01804） | Latent-space Vision Monitor 检测漂移；事件触发截断 + 在线梯度引导重规划 | 需要训练/额外模块；UIBVS 不需要训练 |
| A2C2（arXiv 2509.23224） | 轻量 correction head，每步修正任意 VLA 的 chunk | 第二个学习头；UIBVS 是确定性控制器 |
| VeriVLA（arXiv 2610.21985） | JEPA  latent world model 对候选 chunk 排序；真实任务 50.8%→65.5%；326 ms/触发 | 第二个世界模型；UIBVS 只用 2D 图像 |
| Gated GeoBoN（arXiv 2607.17454） | 训练无关的几何验证选块；跨视角深度重投影 | 需要几何基础模型/多视角预测；UIBVS 不需要深度 |
| PACT-VLA（arXiv 2610.28019） | 用 pre-commit 观测选 chunk；真实任务 60%→82% | 需要多候选 + VLA 自身打分；UIBVS 只做局部伺服 |
| VLA-Feedback（arXiv 2609.21022） | 把最后一步去噪当实时反馈接口；真实 51%→73% | 修改扩散推理；UIBVS 是外挂控制器 |
| FIRe（力残差） | 力感知残差 RL，接触装配 +64.5pp | 需要力传感器；API 没有 |

**空位**：上述方法要么训练 correction head/verifier，要么需要力/触觉，要么需要标定好的相机或几何基础模型。挑战赛恰好没有力/触觉、腕部相机没有内参、单模型规则不欢迎第二个学习模型。UIBVS-MVP 的定位就是 **training-free、calibration-free、force-free**。

## 2. 问题形式化

### 2.1 反馈周期

设：

- `f_c`：evaluator 控制频率（假设 30 Hz，待实测）；
- `T_a`：提交的 `action_chunk_size`；
- `τ`：网络 RTT + 推理 + 图像传输的等效延迟；
- `T_fb`：从「世界变化」到「策略看到变化」的反馈周期。

则：

```math
T_{\mathrm{fb}} \approx \frac{T_a}{f_c} + \tau.
```

| 场景 | `T_a` | `f_c` | `τ` | `T_fb` | 评价 |
|---|---:|---:|---:|---:|---|
| WLA 默认 | 30 | 30 | 50 ms | **1050 ms** | 接触段基本开环 |
| 本方案保守 | 5 | 30 | 50 ms | **217 ms** | 可做 1–2 次接触修正 |
| 本方案乐观 | 5 | 30 | 20 ms | **187 ms** | 需低 RTT |
| 本方案高延迟 | 5 | 30 | 150 ms | **317 ms** | 增益降档 |
| 低控制频率 | 5 | 10 | 50 ms | **550 ms** | 改 `T_a=3` 或只做 PBVS |
| 极低延迟 | 3 | 30 | 20 ms | **120 ms** | 动态任务可用 |

**结论**：`T_a` 必须按实测 `f_c` 和 `τ` 选；不能把 30 步默认值直接搬到远程 API。

### 2.2 特征与目标

设腕部图像中的目标特征为：

```math
\mathbf s = \begin{bmatrix} u \\ v \end{bmatrix}\in\mathbb R^2,
```

例如 HangCup 的杯架立柱中心；期望特征 `s*` 是杯口中心（或孔中心）。误差：

```math
\mathbf e = \mathbf s - \mathbf s^*.
```

只控制 tool frame 的横向自由度：

```math
\mathbf q = \begin{bmatrix} x \\ y \end{bmatrix}\in\mathbb R^2.
```

z（接近/插入/下压）由 VLA 的前馈计划负责；gripper 由 VLA 控制；pivot 先保持零/跟随 VLA。

### 2.3 图像雅可比与 Broyden 更新

局部视觉-运动映射：

```math
\Delta \mathbf s \approx \mathbf J\,\Delta \mathbf q,\qquad
\mathbf J=\frac{\partial \mathbf s}{\partial \mathbf q}\in\mathbb R^{2\times2}.
```

Broyden rank-one 更新：

```math
\mathbf J_{k+1}
= \mathbf J_k
+ \alpha\,\frac{(\Delta \mathbf s_k-\mathbf J_k\,\Delta \mathbf q_k)\,\Delta \mathbf q_k^{\top}}
{\Delta \mathbf q_k^{\top}\Delta \mathbf q_k+\varepsilon},
```

其中 `α∈[0.1,0.3]` 是遗忘/步长，`ε` 防止除零。工程上：

- 初值 `J_0 = diag(j_x, j_y)`，用 D435 标称焦距/深度给一个粗略尺度；不需要精确内参。
- 若 `cond(J) > 10` 或 `|det(J)|` 太小，重置为 `J_0` 或只做一个方向的修正。
- 用最近 `K=5–10` 对数据做 RLS（带遗忘因子）比纯 Broyden 更稳；MVP 先 Broyden，M2 再比较 RLS。

### 2.4 控制律

```math
\Delta \mathbf q
= -\lambda\,\mathbf J_k^{-1}\,\mathbf e_k,
\qquad
\|\Delta \mathbf q\|\le \delta,
```

- `λ∈[0.3,0.5]`：低增益，抗延迟；
- `δ`：每块最多 1 cm 横向修正；
- 死区：`||e|| < 3 px` 时不修正；
- 若连续 3 块饱和，判定目标估计/标定异常，回退 VLA；
- 修正叠加在 VLA 的 5 步轨迹上：`q_cmd(t) = q_vla(t) + Δq`（tool frame）；不是修改 VLA 的语义意图。

### 2.5 延迟稳定性

简化离散积分器：

```math
\mathbf e_{k+1}=\mathbf e_k-\lambda\,\mathbf e_{k-d},
```

其中 `d=τ/(T_a/f_c)` 是延迟块数。特征方程：

```math
z^{d+1}-z^{d}+\lambda=0.
```

- `d=0`：`|1-λ|<1` → `0<λ<2`。
- `d=1`：`z^2-z+λ=0`；稳定域 `0<λ<1`；增益裕度约减半。
- `d=2`：稳定域进一步缩小；必须降增益或加预测。
- 实践：`λ_eff = λ_0/(1+τ/τ_0)`，`τ_0=50 ms`；仿真扫 `τ∈{0,50,100,150} ms`；`T_fb>300 ms` 时关闭 UIBVS，只做 VLA。

### 2.6 可辨识性条件（何时启用）

UIBVS 只在以下条件同时满足时启用：

1. 目标在腕部视野内，跟踪置信度 ≥ 阈值；
2. 特征 inlier ≥ 15 或模板匹配得分 ≥ 0.6；
3. 任务属于刚体接触族（悬挂/叠放/插入/开启）；
4. 当前处于最后 3 厘米阶段（目标尺度/EE 距离/相位规则）；
5. 修正幅值未连续饱和。

任一条不满足 → 回退 VLA 开环；不硬做 UIBVS。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)       │
                    │  ├─ flight recorder                 │
                    │  ├─ wrist feature tracker           │
                    │  ├─ UIBVS controller (2x2 Jacobian) │
                    │  ├─ VLA plan cache (async)          │
                    │  └─ action adapter (WLA 54D → API)  │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared VLA server (GPU)            │
                    │  UnifoLM-WLA-1.0, 30-step plan      │
                    └─────────────────────────────────────┘
```

- 每个端口一个 `PolicyService` 实例，独立 `reset()`、独立 plan cache、独立 UIBVS 状态（Jacobian、feature history）。
- 特征跟踪/UIBVS 是 CPU 线程，不阻塞 websocket；VLA 请求异步、可批处理。
- 共享 VLA server 用 session ID 区分端口；模型权重只有一份，不违反单模型。
- GPU 6B bf16 约 12GB；一张 24GB/40GB GPU 可服务多个端口，具体并发取决于 batch 和序列长度。

### 3.2 接口契约

提交 metadata 示例：

```python
{
    "control_space": "ee",
    "obs_delta_indices": {
        "observation.language":                         [0],
        "observation.images.cam_left_high":             [0],
        "observation.images.cam_right_high":            [0],
        "observation.images.cam_left_wrist":            [0],
        "observation.images.cam_right_wrist":           [0],
        "observation.state.left_ee_pose_gripper_base":  [0],
        "observation.state.right_ee_pose_gripper_base": [0],
        "observation.state.left_gripper":               [0],
        "observation.state.right_gripper":              [0],
        "observation.state.lower_body":                 [0],
    },
    "image_resize": {
        "observation.images.cam_left_high":  [240, 320],
        "observation.images.cam_right_high": [240, 320],
        "observation.images.cam_left_wrist": [160, 120],
        "observation.images.cam_right_wrist":[160, 120],
    },
    "action_chunk_size": 5,
    "token": os.environ["UNIBOT_SUBMISSION_TOKEN"],
}
```

注意：

- `observation.language` 的 offset 必须是 `[0]`（标量字符串，无时间轴）；其余键先用 `[0]` 取当前帧。
- `image_resize` 只对声明过的 key 生效；UIBVS 只需要腕部图，但 VLA 可能需要头部图。
- `action_chunk_size` 是 MVP 的核心超参数：先 5，再扫 1/8/30。
- `ee` 模式的动作是**绝对目标位姿**；WLA 输出的是**相对当前 EE** 的 xyz+rotvec，adapter 必须先 compose 到当前绝对位姿，再叠加 UIBVS 的横向修正。

### 3.3 动作适配（WLA 54D → 挑战赛 21D）

```text
WLA 54D:
  left_ee_rel[6], left_gripper[1], left_hand[6],
  right_ee_rel[6], right_gripper[1], right_hand[6],
  waist[3], torso[3], base_vxvy[2], base_wz[1],
  base_pose_rel[6], height[1], left_leg[6], right_leg[6]

挑战赛 ee 21D:
  left_ee_abs[6], right_ee_abs[6],
  left_gripper[1], right_gripper[1], pivot[7]
```

映射：

1. `left_ee_abs = compose(T_base_ee_left_current, exp(left_ee_rel))`；转 xyz+rpy。
2. `right_ee_abs` 同理。
3. gripper 直通（按挑战赛的 0–1 方向校验）。
4. `pivot = [vx, vy, wz, yaw, pitch, roll, height]`，从 WLA base/waist 组合；具体符号/顺序必须用 `example_env.py` 和单任务通道验证。
5. 腿部/灵巧手在挑战赛 `ee` 模式下不直接下发；若 `pivot` 需要下身体，按官方 WLA server 的 `action.pivot` 语义映射。

**关键细节**：WLA 的每个未来动作是「相对 plan-time 当前 EE」的位姿（compose 后才是 base 系绝对目标），不是累积增量；adapter 必须先把整个 30 步 compose 成 base 系绝对目标，再按 5 步切片。否则切片后的第 6–30 步会以错误的锚点解释，产生系统性偏移。

**帧/TCP 风险**：WLA 的 EE 帧与挑战赛的 `*_ee_pose_gripper_base` 帧可能差一个 TCP/夹爪长度偏移；必须用 `example_env.py` 的观测和真实数据做一次手眼/工具坐标校准（平移 ≤1 cm、旋转 ≤2°）。这是 M0 的第一验证项。

**风险**：`pivot` 的 7 维语义在挑战赛 README 中只写「Lower-body / pivot target」，没有逐维定义；这是 adapter 的第一验证项。若语义不匹配，先返回全零 pivot（保持下身体不动），只验证双臂；不要猜符号。

### 3.4 `get_action` 伪代码

```python
import numpy as np

class UIBVSPolicy:
    def __init__(self, vla, tracker, adapter, token,
                 T_a=5, lam=0.4, dmax=0.01, deadband_px=3.0,
                 task_family="hang"):
        self.vla = vla
        self.tracker = tracker          # classical CV: template/color/ellipse
        self.adapter = adapter          # WLA 54D -> API 21D
        self.token = token
        self.T_a = T_a
        self.lam = lam
        self.dmax = dmax
        self.deadband = deadband_px
        self.task_family = task_family
        self.J = np.diag([0.002, 0.002])  # rough prior; refine online
        self.prev_s = None
        self.prev_ee = None
        self.plan = None
        self.plan_idx = 0
        self.saturated = 0
        self.reset_episode()

    def reset_episode(self):
        self.prev_s = None
        self.prev_ee = None
        self.plan = None
        self.plan_idx = 0
        self.saturated = 0
        self.J = np.diag([0.002, 0.002])

    def get_action(self, obs):
        wrist = obs["observation.images.cam_left_wrist"][-1]  # current frame
        ee = obs["observation.state.left_ee_pose_gripper_base"][-1]
        s = self.tracker.track(wrist)      # [u, v] or None

        dq = np.zeros(2)
        if s is not None and self.gate(obs, s):
            if self.prev_s is not None and self.prev_ee is not None:
                ds = s - self.prev_s
                dq_actual = self.lateral_motion(ee, self.prev_ee)  # tool x/y
                self.J = broyden(self.J, ds, dq_actual,
                                 alpha=0.2, eps=1e-6)
            e = s - self.tracker.desired()
            if np.linalg.norm(e) > self.deadband:
                try:
                    dq = -self.lam * np.linalg.solve(self.J, e)
                except np.linalg.LinAlgError:
                    self.J = np.diag([0.002, 0.002])
                    dq = np.zeros(2)
                dq = clip_norm(dq, self.dmax)
                self.saturated = self.saturated + 1 if np.linalg.norm(dq) >= self.dmax else 0
                if self.saturated >= 3:
                    dq = np.zeros(2)       # abort servo; fall back to VLA
                    self.saturated = 0
            self.prev_s = s
            self.prev_ee = ee
        else:
            self.prev_s = None
            self.prev_ee = None

        plan = self.get_plan(obs)          # async VLA; cached if still running
        chunk = plan[self.plan_idx:self.plan_idx + self.T_a]
        self.plan_idx += self.T_a
        if self.plan_idx >= len(plan):
            self.plan_idx = 0
            self.plan = None               # force next async request

        chunk = apply_tool_lateral(chunk, dq)  # absolute EE poses + tool x/y offset
        return self.adapter.to_api(chunk, obs, self.token)

    def gate(self, obs, s):
        if not self.tracker.visible(s):
            return False
        if not self.in_last_phase(obs, s):
            return False
        if self.task_family not in {"hang", "stack", "insert", "open"}:
            return False
        return True

    def in_last_phase(self, obs, s):
        # rule-based: target scale / EE-target distance / gripper state
        return self.tracker.scale(s) > 0.6 or self.ee_close(obs)

    def get_plan(self, obs):
        if self.plan is None or self.plan_idx == 0:
            self.plan = self.vla.predict(obs)   # in production: async future
        return self.plan
```

说明：

- `tracker` 用**经典 CV**（模板匹配/颜色块/椭圆/直线），不用第二个神经网络；这是单模型合规的关键。
- `prev_ee`/`lateral_motion` 用 EE 位姿差分投影到 tool frame；不需要相机标定。
- `apply_tool_lateral` 把 2D 修正转成 tool-frame 的 x/y 偏移，叠加到 VLA 的绝对 EE 轨迹上；z/roll/pitch/yaw 不动。
- `get_plan` 在生产环境应异步：VLA 在后台跑，UIBVS 用缓存 plan；避免 VLA 推理阻塞 `get_action`。

### 3.5 状态机

```text
INIT ──first obs──▶ APPROACH ──target visible + close──▶ SERVO
  ▲                    │                                  │
  │                    │                                  ├─ error < deadband ──▶ CONTACT
  │                    │                                  │                         │
  │                    │                                  │                         └─ task done ──▶ DONE
  │                    │                                  │
  │                    └── target lost ──▶ VLA_OPEN_LOOP ◀─── saturation/occlusion
  │
  └──────────────────────── reset() ◀──────────────────────── DONE
```

- `APPROACH`：VLA 主导；UIBVS 不启用（避免过早干扰）。
- `SERVO`：最后 3 厘米；UIBVS 2D 横向修正；z 由 VLA 前馈。
- `CONTACT`：误差进入死区；保持修正或交给 VLA 的轴向动作；gripper 由 VLA 控制。
- `VLA_OPEN_LOOP`：目标丢失/修正饱和；回退 VLA；不再硬做伺服。
- `DONE`：任务成功/失败/超时；`reset()` 清空 Jacobian/feature history。

## 4. MVP 阶梯与实验设计

### 4.1 M0：基线/接口（2–3 天）

| 项 | 内容 |
|---|---|
| 目标 | 官方 WLA + API adapter + N 端口；单任务通道跑通 HangCup |
| 验证 | 握手、token、动作形状、reset、p99 延迟 |
| 产出 | 基线成功率/步骤分/延迟日志；`pivot` 语义结论 |
| 失败动作 | 接口不通 → 修接口；`pivot` 不匹配 → 先零 pivot 只做双臂 |

### 4.2 M1：chunk governor（2 天）

| 项 | 内容 |
|---|---|
| 变量 | `T_a ∈ {1, 5, 8, 30}`；同一 VLA、同一任务、同一初始条件尽量配对 |
| 指标 | 成功率、步骤分、p50/p99 延迟、timeout、动作抖动 |
| 通过 | 找到 `T_a` 的折中；p99 ≤150 ms；无 timeout 激增 |
| 失败 | 全部抖动/超时 → 回退大 chunk；只做 VLA |

### 4.3 M2：离线 UIBVS（3–4 天）

| 项 | 内容 |
|---|---|
| 数据 | HangCup 1,043 条成功演示；按 episode 划分 train/val，禁止相邻帧跨 split |
| 特征 | 杯架立柱（颜色/直线）+ 杯口（椭圆/颜色）；模板来自演示关键帧 |
| 扰动 | 在最后 3 厘米注入图像平移/缩放（模拟横向/深度偏差） |
| 指标 | 收敛率、稳态误差、超调、雅可比条件数、跟踪丢失率 |
| 通过 | 注入误差收敛 ≥80%；无持续振荡；跟踪丢失 <20% |
| 失败 | 特征不稳 → 换特征/换任务；雅可比不稳 → RLS/信任域 |

**限制**：离线回放只能验证特征跟踪和控制器稳定性，不能证明真机成功率；真机必须过 M3。

### 4.4 M3：真机 HangCup A/B（1 周）

| 项 | 内容 |
|---|---|
| 任务 | HangCup（单任务不计分通道） |

| 指标 | 成功率、步骤分、完成时间、p99、目标可见率、修正幅值、回退次数 |

| G1 | 离线 UIBVS 是否收敛？ | 注入误差收敛 ≥80%；无振荡 | 换特征/RLS/换任务 |
| G2 | 延迟下是否稳定？ | `τ=0–150 ms` 稳定；超调 <20% | 降增益/加 chunk/关伺服 |
| G3 | 真机 HangCup 是否涨点？ | +10pp；p99 ≤150 ms | 不提交 servo 版本 |
| G4 | 同族是否可复制？ | 3 个任务中 ≥2 个 +10pp | 只保留有效任务 |
| G5 | 恢复是否有效？ | 检测 ≤200 ms；恢复 ≥50% | 只做离线分析 |
| G6 | 32 任务干跑是否稳定？ | 端口隔离、reset 干净、内存不涨 | 回退基线 |
| G7 | 消融是否支持因果？ | servo on > off；2D > 无伺服；Broyden > 固定 J | 保留有效部分，砍掉无效 |

## 5. 任务族组合与竞赛策略

### 5.1 任务族先验

| 族 | 任务（先验） | 数量 | 最后 3 cm 杠杆 | MVP 优先级 |
|---|---|---:|---|---|
| 悬挂/叠放 | HangCup、StackBowls、PaperCupStacking、StackCups、ArrangePlates、StoreRacket | ~6 | 高 | P0（HangCup 先） |
| 插入 | DisconnectEthernet、PlugCharger、PlugInEthernet、ArrangeTestTubes、Unlock、SyringeWaterTransfer | ~6 | 高 | P1 |
| 开启/闭合 | OpenPillBottle、ToolboxStorage、ZipUp、PackBag、PlacePhotoFrame | ~5 | 高 | P1/P2 |
| 抓放/分类 | FruitCollection、FruitSorting、ColorArrangement、PickOutBatteries、OrganizeTools、OrganizeStationery、PackDoll、PackPhone、StoreCups、RemovePinnedNote、ConveyorSorting 等 | ~12 | 中/低 | P2 |
| 变形/长程 | FoldTowel、PackDoll、SpellRobot、ToolboxStorage、StoreRacket | ~3–5 | 低/中 | P3 |

这张表是**先验**，不是结论；单任务通道跑完后，用 `q_f`（失败发生在最后 3 厘米的比例）× `Δ_f`（UIBVS 条件增益）/ `cost_f` 重排。

### 5.2 收益算术

- 32 任务等权：一个任务 +10pp = `+0.31pp` 全局。
- 6 个悬挂/叠放 + 6 个插入 + 5 个开启 = 17 个任务；各 +10pp → `17/32×10≈+5.3pp`；各 +15pp → `+8.0pp`。
- human 轴占 20%；human 轴 +10pp → `+2pp`。
- 保守目标 +3–5pp；乐观 +7–8pp；M3 不过就不提交。
- 320 trials 下，`p≈0.25` 的单次标准误约 `sqrt(0.25×0.75/320)=2.42pp`；配对设计会低一些，但**不要声称 +1–2pp 是结论**。

### 5.3 单任务通道协议

1. 任务：HangCup（MVP）→ StackBowls（同族）→ PlugInEthernet（插入族）→ ZipUp（开启族，防回归）。
2. 每任务 5 次 A/B（servo off/on）；同 VLA/`T_a`；尽量同初始条件。
3. 指标：成功率、步骤分、完成时间、p99、目标可见率、修正幅值、回退次数。
4. 通过：≥3/5 任务 +10pp；非接触/变形任务不回归 >5pp；否则不提交 servo 版本。
5. 再扫 `T_a∈{3,5,8}` 和 `image_resize` 两档；选 p99 与成功率的最佳折中。
6. 最后才跑 32×10 正式评测；不要用正式 320 trials 做未验证的 A/B。

### 5.4 提交节奏

- 先邮件确认：是否允许多次计分提交、N 是多少、`pivot` 逐维语义、控制频率。
- 若允许多次：先交安全基线（WLA + chunk 30 + 官方 adapter）锁「更早提交」tie-break；再交 UIBVS 版本。
- 若只允许一次：M3/M4 通过后再交；不要用未验证的 servo 版本赌 320 trials。
- 部署：N 未知；按 N=3 设计；每端口独立 `reset()`/UIBVS 状态；VLA 可共享；保持 p99 稳定，避免动作异常。

### 5.5 资源与时间表

| 阶段 | 时间 | 交付 | 退出条件 |
|---|---:|---|---|
| M0 基线/接口 | 1 周 | WLA + adapter；token/`pivot` 验证；chunk 30/5 基线 | 单任务通道跑通 |

## 6. 风险与合规

### 6.1 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 只用离线数据做特征/相位分析；线上只有 VLA | 最低 | 保守备选 |
| C2 确定性控制器 | UIBVS 是几何/控制律，无学习权重；VLA 是唯一学习模型 | 低；需向官方说明 | **主推** |
| C3 同 checkpoint 特征 | 特征用 VLA 同一 checkpoint 的 encoder，不加载第二个模型 | 低–中；需说明 | 需要强特征时用 |

禁止：加载第二个学习策略/残差网络/独立视觉编码器做在线决策。UIBVS 的跟踪器必须是经典 CV（模板/颜色/椭圆/直线），不能是 SAM/DINO/第二个 VLM。

**新颖性边界**：UIBVS 算法本身是 20+ 年的经典工作（Broyden/RLS/无标定伺服），本报告不主张新控制理论。组合层面的新意是：(1) 在无腕部内参、无深度、无力/触觉、单模型约束下，把 2×2 UIBVS 作为 VLA 的外挂闭环；(2) 用 chunk governor 把反馈周期压到 187–317 ms；(3) 用任务族复制把单任务 +10pp 放大到 17 个任务；(4) 用 HangCup 腕部帧和 M3 配对 A/B 构成可证伪证据链。若被问「这不就是经典 IBVS 吗」，答案是「是；但比赛约束下没人把它做成最小可部署闭环，我们证明的是组合与工程，不是新算法」。

### 6.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定为第二个模型 | C2；提交材料写清楚；跟踪器无学习权重 |
| 腕部目标不可见/遮挡 | UIBVS 无效 | G0 逐任务测；回退 VLA/头双目 |
| 特征跟踪不稳 | 错误修正 | 模板+颜色+几何多特征；置信度门控；丢失即回退 |
| 雅可比不稳定 | 振荡/发散 | 低增益、死区、饱和、信任域、RLS/重置 |
| RTT 高 | 反馈慢 | `T_a` 扫描；降增益；预测补偿；回退大 chunk |
| VLA 与伺服冲突 | 动作抖动 | 只在最后 3 cm 启用；修正限幅；tool-frame 小偏移 |
| 透明/反光/变形 | 特征失败 | 只对刚体任务启用；腕部 2D + 夹爪滞止兜底 |
| 步骤分变差 | 排名下降 | 修正限幅/平滑；A/B 同时看成功率和步骤分 |
| 评测噪声 | 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |
| 数据泄漏 | 离线指标虚高 | 按 episode/session/物体/背景分组划分；相邻帧不跨 split |
| 安全 | 碰撞/超调 | 限速/限幅/最大重试；饱和即停；人工急停 |
| `pivot` 语义不一致 | 动作被拒/机器人不动 | M0 用 `example_env.py` 验证；零 pivot 回退 |
| 提交次数限制 | 无法多次 A/B | 邮件确认；单任务通道先验证；一次提交则保守 |
