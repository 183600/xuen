# 第 13 轮 · STATEKEEPER：把 32 项任务的公开评分细则编译成「可回退状态机」，用证据信念和对话式修复补上长程执行的记忆缺口

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份已再次确认：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API；不是 Unibots UK、AGIBOT World Challenge 或其他同名赛事。本轮是新灵感循环第 1 轮，但与文件中的第 10–12 轮连续：不推倒 FACT-VLA、GEO-RESIDUAL、CHUNK-SERVO，而是在它们之上补一层「任务级状态监督」。三个灵感词是「状态机」「原型验证」「对话管理」。

## 0. 先给结论：不到 30% 的另一个共享瓶颈，是「任务级状态」而不是「动作级精度」

截至 2026-10-31，公开榜单 JSON 仍是同一组 8 个预览模型：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、PI-0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。榜单 HTML 仍显示「即将发布 / Coming Soon」，`generated_from` 仍是 `gen_leaderboard.py`，没有新增真实评测结果；因此这些分数只能当“预览上限/难度信号”，不能当 SOTA 或任务难度表。

第 12 轮 CHUNK-SERVO 的判断仍然成立：所有头部模型共享“最后 3 厘米”的执行瓶颈。但本轮要补一个同样重要的判断：

> **它们还共享“任务级状态”瓶颈：一条固定语言指令要覆盖 2–5 个评分步骤、15 个任务含重复/计数子目标、9 个任务的官方人为干扰会直接把已完成步骤改回去；而官方 33k 演示以成功示范为主、没有失败/回退标注，模型没有从失败/回退中学过“我现在在哪一步、上一步是否被撤销、下一步该重做哪一步”。**

三个新核实的事实把这个问题变得具体：

1. 官方挑战赛页面为 32 个任务各提供了一份 `tasks_v2/<slug>/info.json`，里面有**公开评分细则**：合计 **94 个评分步骤**，每任务 2–5 步、满分 100；其中 **25/32 个任务的最后一步值 40–50 分**，最后一步平均 **39.8 分**，高于第一步平均 **35.5 分**。
2. 官方数据集的 `tasks.parquet` 每个任务有 **5 条英文同义指令**，32 任务共 **160 条**；这说明评测语言不是一条固定模板，而是有改写分布。
3. 官方 `info.json` 的 `generalization` 字段给出了每个任务在未见物品/人为干扰下的具体扰动注记；其中至少 **9 个任务**的人为干扰会“撤销”已完成步骤（叠好再翻开、拉上再拉开、合上再打开、插上再拔起、摆好再拿走）。

所以本轮的押注是 **STATEKEEPER**：

> 把官方 32 项任务的公开评分细则编译成一台**非单调、可回退的分层状态机**；用几何、演示检索、同一 VLA 的动作一致性维护“子目标完成信念”；用阶段提示调度同一个 VLA；把人为干扰当作对话中的 **barge-in**，先撤回承诺、再局部修复，而不是整任务重来。全程不新增学习模型，VLA 仍是唯一动作模型。

一句话：**从“预测下一段动作”升级到“记住做到哪、发现做回去、只重做该重做的那一步”。**

## 1. 本轮新核实的事实（只列会改变方案的）

### 1.1 规则：单模型、32 任务、10 次/任务、5 类泛化各 2 次、单任务不计分通道

参赛手册（2026-10-31 通过 `r.jina.ai` 复核，中文版；与 2026-10-28 一致）明确：

- 所有任务须基于**同一模型**完成，不得混合多个模型；模型类型不限（World Model、VLA 均可）。
- 32 个任务，每个任务 10 次独立运行；5 类泛化各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
- 单次真机执行上限 **180 s**；排名先看 32 任务总平均成功率，成功率相同看总步骤分，再相同看更早提交。
- 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态必须隔离。
- 只设通才模型赛道；另有**不计分的单任务测试通道**，可用于单任务成功率/步骤分验证。

**对方案的约束**：STATEKEEPER 必须是每端口独立、CPU 轻量、不抢 GPU 的监督器；不能是第二个策略模型；单任务通道是做 A/B 的唯一安全场所。

### 1.2 API：语言是「整段固定字符串」，chunk 内没有新观测

提交模板 README（2026-10-31 复核）明确：

- 观测：四路 RGB 480×640（`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`）；双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`。
- `observation.language` 是 **scalar `str`**，描述当前 episode 的任务，**整段不变、没有时间轴**；offset 必须是 `[0]`。
- 动作：`joint` 或 `ee` 互斥；`action_chunk_size` 固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action`；chunk 内没有新观测，也没有打断机制。
- **没有 depth、camera_info、force/torque、tactile**；只有 RGB + 本体。
- 评测端逐调用记录延迟、波动和动作统计规律，作为结果可信度的一部分。

**关键推论**：不要指望“多轮对话”或“中途澄清”。所谓「对话管理」只能是**策略内部的对话**：把固定指令当作 system prompt，把每个子目标当作一次 assistant turn，把观测/人为干扰当作 user turn / barge-in。真正的接口层只有 observation→action，语言不会变。

### 1.3 公开评分细则：94 个步骤、每任务 100 分、最后一步最值钱

挑战赛页面 `challenges.html` 的 JS 从 `tasks_v2/<slug>/info.json` 加载任务卡；2026-10-31 逐个抓取 32 份，合计：

| 项 | 数值 |
|---|---:|
| 任务数 | 32 |
| 评分步骤总数 | **94** |
| 每任务步骤数 | 2 步 11 个 / 3 步 14 个 / 4 步 5 个 / 5 步 2 个 |
| 每任务满分 | 32/32 都是 100 |
| 难度 | Easy 12 / Medium 12 / Hard 8 |
| 最后一步 ≥40 分的任务 | **25/32（78%）** |
| 最后一步平均分 | **39.8**（第一步 35.5） |
| 含编号物体或 all/remaining 量化子目标的任务 | **15/32** |
| 含 close/zip/lock 终局步骤的任务 | **8/32** |

典型例子（原文见 §11）：

- `T01 HangCup`：抓住杯把（50）→ 挂到杯架标记位置（50）。
- `T04 FruitSorting`：水果 1 放对色盘（30）→ 水果 2（30）→ 水果 3（40）。
- `T09 ToolboxStorage`：先收两件工具（25）→ 收完剩余（25）→ 合盖（25）→ 上锁（25）。
- `T19 ZipUp`：拉直收纳袋（50）→ 拉上拉链（50）。
- `T16 FoldTowel`：拉直（20）→ 上下对折（20）→ 左折（20）→ 右折（20）→ 折好放旁边（20）。

**战略含义**：最后一步不是“收尾”，而是分值最高、最容易在成功后被自己或人碰坏的一步。一个只会开环执行 chunk 的模型，可能在最后一步完成后继续动，把刚挂好的杯子/刚叠好的毛巾/刚拉上的拉链弄回去；一个非单调状态机可以在这里 **freeze + verify**。

### 1.6 榜单：仍是 8 个预览模型，没有新的真实结果

2026-10-31 复核：

- `leaderboard_data.json` 仍是 8 个模型，分数与 2026-10-28 完全一致。
- `generated_from` 仍是 `gen_leaderboard.py`；对 8 模型 ×32 任务做 `step_score ~ success_rate` 回归仍是 R²>0.999999、最大残差<0.006；任务成功率仍出现 27.29%、27.85%、38.43% 等非 10% 整数倍。
- `leaderboard.html` / `runs.html` 静态壳仍显示「即将发布 / Coming Soon」；`details.html` 仍显示“Test Video Details / Loading…”。

**结论**：不把榜单当 SOTA、当任务难度表或当失败分布；只把它当“赛事方预览上限”。本轮不从榜单任务排名挖创新点，只从公开规则、rubric、数据和模型家族路线挖。

### 1.7 头部方案的做法与瓶颈：四种路线，同一个“任务级状态”缺口

| 模型家族 | 公开路线 | 优势 | 与本轮相关的瓶颈 |
|---|---|---|---|
| **MolmoAct2** | Ai2 的 action reasoning model；Molmo 2-ER + action expert + adaptive depth reasoning；强调 3D 空间推理、推理加速、无 per-task 微调 | 3D/空间语义强；双臂 | 仍是开环 chunk；长程步骤/计数/回退没有显式状态 |
| **WALL-OSS-0.5** | X Square 的 4B VLA（3B VLM + action expert）；公开材料称 15 个真机任务 60.5% average task progress | 预训练直接可用；progress 高 | progress ≠ success；最后一步失败就 0 分；步骤状态靠隐式 |
| **DreamZero** | 14B Wan2.1 video-diffusion world-action model；预测未来视频再出动作 | 长程预测/规划 | 14B 推理重；世界模型不直接解决“现在第几步/上一步是否被撤销” |
| **π0.5** | Physical Intelligence 的开放世界泛化 VLA | 语义/新场景泛化 | 接触密集任务精度；长程状态 |
| **GigaBrain-0** | 世界模型生成数据 + VLA | 数据效率/泛化 | 生成数据物理保真度；最后 3 厘米 |
| **GR00T N1.5** | NVIDIA 通用人形 VLA | 生态/embodiment | 任务特定精度；数据覆盖 |

共同点：

- 都输出 action chunk，chunk 内不看新图；**没有显式的“任务进度”变量**。
- 公开路线普遍以**成功演示**为主训练；官方 33k 数据也没有失败/回退/被人改回去的标注。
- 模型越大，chunk 越长，越不反应；世界模型解决“想象未来”，不解决“现在第几步”。
- 单模型规则堵死了“再加一个学习残差/第二个 VLM 裁判”的捷径；但**确定性状态机 + 演示检索**不是第二个模型。

### 1.8 相关工作的定位：别人已经做了“阶段”，但没做“可回退的评分细则状态”

2026-10-31 检索到的近期工作（用于定位，不作为本方案的依赖）：

- **ActionGround**（arXiv 2609.33256）：phase-aware finite-state machine 包住 frozen VLA，在 MuJoCo 状态上做 approach/grasp/transport/place 四阶段修正，<1 ms 开销。差别：它用**仿真特权状态**、四个通用阶段；我们用**官方 rubric 的 94 个任务步骤**、只用 RGB/本体、且支持回退。
- **Harness VLA**（arXiv 2607.08448）：memory-guided agent + 冻结 VLA + 解析 primitive，在 LIBERO-Pro/RoboCasa 上大幅涨点。差别：它引入 LLM coding agent/额外规划器；我们要**单模型合规**，不引入第二个学习模型。
- **FLARE**（arXiv 2608.26645）：Retry/Reset，用 online MLLM monitor + 学习的 reset skills。差别：需要第二个模型和新技能；我们不训新策略。
- **VLAC-Cut**（InternRobotics）：非单调 progress critic，基座 Qwen3-VL-30B。差别：30B 裁判太重，且是第二个模型；我们只用确定性证据。
- **PACE**（arXiv 2610.07917）：stage-consistent long-horizon manipulation，解决 stage confusion。差别：它改模型内部 context；我们是模型无关的 test-time wrapper。
- **Kintsugi-VLA**（arXiv 2609.31048）：把失败 rollout 转成 recovery 数据。差别：需要仿真/特权 expert 和训练；我们只用官方演示 + 合成扰动验证。

**空白**：在一个**单模型、RGB-only、固定语言、远程 API** 的竞赛里，把**公开评分细则**编译成**非单调状态机**，用**演示检索 + 同一 VLA 的提示调度**做在线监督与修复——这条组合还没有被占。

## 2. 诊断：三个“状态缺口”

把一次失败拆开看：

```text
固定指令 ──▶ VLA ──▶ 30 步 chunk ──▶ 世界
                ▲                         │
                │                         ▼
          没有“第几步”变量          人把已完成步骤改回去
```

### 2.1 缺口一：状态混叠 / 计数丢失

15/32 个任务含重复/计数子目标（编号物体或 all/remaining 量化；水果 1/2/3、工具 1–4、电池 1–3、试管 1–3、盘子 1–3、杯子 1–3、碗 1–3、文具 1–3；折叠等多步重复另计）。当前观测可能和“上一步”长得一样：抓完第一个水果和抓第二个水果的画面几乎相同。VLA 的短历史/单帧输入没有符号计数；它可能重复抓同一个、漏掉一个、或提前宣布“全部完成”。

### 2.2 缺口二：进度不可逆假设 vs 人类回退

多数策略/世界模型隐式假设任务进度单调递增。但官方 human 轴明确会“拉上再拉开、合上再打开、叠好再翻开、插上再拔起”。一个单调状态机在检测到“已完成步骤被撤销”时不会回退，只会继续执行后面的步骤，最后失败。**官方演示数据里没有这种负样本/标注**，所以不能指望端到端模型自己学会。

### 2.3 缺口三：一条固定指令 vs 多阶段执行

`observation.language` 整段不变；一个 5 步任务（FoldTowel、OrganizeStationery）在最后一步仍然收到同一条“把毛巾叠好放旁边”。模型没有“当前子目标”的显式提示；它只能从像素和隐式训练分布里推断阶段。对长程任务，这是不必要的负担。

### 2.4 为什么现在能做

- 官方 rubric 公开：32 份 `info.json`，94 个步骤，每步有分值和英文描述；这是现成的“任务骨架”。
- 160 条同义指令：可做意图路由和语言鲁棒性验证。
- 33k 官方演示：可做**演示检索**（当前帧最像哪个成功阶段），不需要第二个学习模型。
- 头部双目已标定，腕部也有内参：可做几何证据（距离、高度、重叠、夹爪开合）。
- 官方 WLA 模型服务器支持**每条请求覆盖 instruction**（`obs["instruction"]`/`obs["task"]` 优先于启动参数）：阶段提示调度不需要改模型。
- 单任务不计分通道：可在不烧正式 320 trials 的情况下做 A/B。

## 3. 方法：STATEKEEPER

### 3.1 总架构

```text
                    ┌────────────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1)        │
                    └───────────────┬────────────────────────────┘
                                    │ obs / action chunk
                                    ▼
                    ┌────────────────────────────────────────────┐
                    │  Per-port STATEKEEPER (CPU, ~10ms)         │
                    │  ├─ intent router (160 paraphrases)         │
                    │  ├─ rubric contract + FSM (94 states)       │
                    │  ├─ belief/evidence fusion                  │
                    │  ├─ barge-in detector + repair policy       │
                    │  ├─ phase prompt bus                        │
                    │  └─ CHUNK-SERVO adapter                     │
                    └───────────────┬────────────────────────────┘
                                    │ async plan + prompt
                                    ▼
                    ┌────────────────────────────────────────────┐
                    │  Shared VLA server (GPU)                    │
                    │  UnifoLM-WLA-1.0 / VLA-0, 30-step chunk     │
                    └────────────────────────────────────────────┘
```

- **唯一学习模型**：VLA（官方 WLA 微调 action head，或选手自选 VLA）。
- **确定性监督器**：FSM、证据融合、意图路由、修复策略；无学习权重。
- **数据资产**：33k 官方演示 → 阶段检索索引；不是第二个模型。
- **低层执行**：沿用第 12 轮 CHUNK-SERVO 的 5 步闭环/视觉伺服；STATEKEEPER 只决定“当前做哪个子目标、要不要重做、什么时候冻结”。

### 3.2 RUBRIC-COMPILER：把公开评分细则变成任务契约

对每个任务抓取 `tasks_v2/<slug>/info.json`，编译成统一 schema：

```json
{
  "task_id": "T01",
  "slug": "hang_the_cup",
  "instructions": ["Hang the cup on the marked spot...", "..."],
  "objects": [{"role": "cup", "attrs": []}, {"role": "rack", "attrs": ["marked_spot"]}],
  "steps": [
    {"id": "s1", "points": 50, "verb": "grasp", "object": "cup.handle",
     "post": ["gripper_closed_on(handle)", "cup_moves_with_gripper"],
     "prompt": "Grab the cup handle."},
    {"id": "s2", "points": 50, "verb": "hang", "object": "cup", "target": "rack.marked_spot",
     "post": ["cup_hangs_on(rack.marked_spot)"],
     "prompt": "Hang the cup on the marked spot."}
  ],
  "order": ["s1", "s2"],
  "time_budget_s": 180
}
```

对重复/计数任务，用 `FOR` 模板：

```json
{
  "loop": {"over": "fruits", "count": 3, "order": "any"},
  "steps": [
    {"id": "s1", "points": 30, "verb": "pick_place", "object": "fruit[0]",
     "target": "plate.color(fruit[0])", "prompt": "Place the first fruit on its matching plate."},
    {"id": "s2", "points": 30, "verb": "pick_place", "object": "fruit[1]",
     "target": "plate.color(fruit[1])", "prompt": "Place the second fruit on its matching plate."},
    {"id": "s3", "points": 40, "verb": "pick_place", "object": "fruit[2]",
     "target": "plate.color(fruit[2])", "prompt": "Place the last fruit on its matching plate."}
  ]
}
```

对顺序/颜色约束，用 `order` + `role`：

```json
{
  "order": ["red", "green", "yellow"],
  "direction": "right_to_left",
  "steps": [
    {"id": "s1", "points": 30, "prompt": "Place the red block in the rightmost position."},
    {"id": "s2", "points": 30, "prompt": "Place the green block in the middle position."},
    {"id": "s3", "points": 40, "prompt": "Place the yellow block in the leftmost position."}
  ]
}
```

**关键点**：契约只描述“做什么/顺序/分值/后置条件”，不写死轨迹；具体动作仍由 VLA 生成。这样既利用公开 rubric，又不把方案变成 32 个手工策略。

### 3.3 意图路由：160 条已知指令 + 低置信度回退

在线第一件事：把 `observation.language` 映射到任务 ID/契约。

```text
1) 精确/规范化匹配 160 条官方同义指令 → task_id（命中率 100%）
2) 英文 TF-IDF/字符 n-gram 最近邻 + top-5 投票 → task_id + margin
3) 中文关键词表（zh_name/zh_desc）→ task_id
4) margin < θ 或 top-1 票数接近 → 不硬猜：
   - 用原句直接喂 VLA；
   - 只启用「通用模板 FSM」（无任务特定后置条件）；
   - 或对两个候选各跑 1 个 chunk，用同一 VLA 的动作似然/一致性做 clarification。
```

**本轮离线预实验（CPU，2026-10-31，纯 Python TF-IDF，词 1–2 gram + sublinear tf + 平滑 idf + L2，leave-one-out top-5 投票）**：160 条指令的准确率是 **89.4%**（143/160），17 个错误集中在易混簇：PlugInEthernet↔DisconnectEthernet（6）、OrganizePencilCase↔OrganizeStationery/PackBag/ZipUp（5）、StoreCups↔HangCup（2）、StorePaddle↔PackBag/ZipUp（2）、PaperCupStacking↔StoreCups（1）、ToolboxStorage↔PickOutBatteries（1）。同任务内平均余弦 0.336，跨任务 0.029（约 11.8× 可分）。**设计结论**：已知指令走精确匹配（160/160）；未见改写走低置信度回退，不硬猜；不要把 89% 的路由器当成 100%。

### 3.4 非单调信念状态：完成不是布尔值，而是可撤回的承诺

对每个子目标 `i` 维护：

- `done_i ∈ {0,1}`：已承诺完成；
- `b_i ∈ [0,1]`：完成信念；
- `last_evidence_i`：最近一次证据；
- `regress_count_i`：回退次数；
- `retry_count_i`：重试次数。

证据四路（全部确定性/复用同一 VLA）：

| 证据 | 来源 | 例子 | 成本 |
|---|---|---|---|
| `e_geom` | 本体 + 双目几何 | 夹爪闭合、物体随夹爪移动、物体进入目标 ROI、堆叠高度/重叠 | <1 ms |
| `e_retrieval` | 33k 官方演示的最近邻 | 当前帧最像哪个任务的哪个阶段；top-k 阶段投票 | 3–10 ms |
| `e_action` | 同一 VLA 的动作一致性 | 用已执行 chunk 分别与当前/下一子目标 prompt 的动作比较：更像下一子目标 → 当前步可能已完成 | 2 次额外 VLA（只在候选转移点） |
| `e_time` | 演示阶段时长先验 | 某阶段通常持续数百毫秒到数秒；超时/过早 → 置信度调整 | <1 ms |

融合（固定权重、离线标定，不训练策略）：

```text
logit b_i(t) = logit b_i(t-1) + w_g Δe_geom + w_r Δe_retrieval
               + w_a Δe_action + w_t Δe_time
```

转移规则：

```text
if b_i > θ_done and guard_i:      done_i = 1; c = i+1
if done_i and b_i < θ_regress:    done_i = 0; c = i; regress_count_i += 1
if edit_score > θ_edit:           state = REPAIR (barge-in)
if timeout_i:                     state = REPAIR / skip if independent
```

**非单调的关键**：已完成的步骤以低频率（每 5–10 个 chunk）重新检查；一旦证据显示被撤销，就撤回承诺并回到该步。这不是“失败重试”，而是“世界变了，状态要跟着变”。

### 3.5 对话式修复：把人为干扰当作 barge-in

把一次 episode 看成一场内部对话：

| 对话概念 | 机器人对应 |
|---|---|
| system prompt | `observation.language`（整段固定） |
| user turn | 新观测 / 人为干扰 / 物体被移动 |
| dialogue state | 子目标信念 + 对象身份 + 计数 + 顺序 |
| assistant turn | 当前子目标的阶段提示 |
| barge-in | 人把已完成步骤改回去 / 把目标拿走 |
| repair | 暂停 → 重定位 → 更新信念 → 只重做受影响子目标 |
| confirmation | 后置条件复查 / 完成后 freeze |
| dialogue policy | continue / retry / reground / abort |

修复策略（代价敏感，优先保成功、其次保步骤分）：

```text
REPAIR:
  hold 0.3–0.5 s（安全）
  re-observe：头部/腕部转向最后已知目标位置
  update b_i, target pose
  if b_i > θ_done:        resume c = i+1
  elif b_i > θ_partial:   re-prompt i; retry once with conservative gain
  elif target visible:    reground; retry once
  else:                   abort subgoal; if independent, go to next; else safe stop
```

**与“整任务重来”的差别**：只重做被撤销的那一步；已完成的其它步骤保留。这样在 human 轴上不会把时间浪费在从头再来，也不会把已完成的步骤碰坏。

### 3.6 阶段提示调度：给同一个 VLA 一次“当前该做什么”的对话轮

在线 prompt 三选一：

- `P0`：原句（基线）。
- `P1`：当前子目标句（如 “Grab the cup handle.”）。
- `P2`：原句 + 当前子目标（推荐；保留全局上下文，降低分布漂移）。

```text
prompt = f"{original_instruction} Current subgoal: {step.prompt}"
```

对重复任务加计数/顺序：

```text
"Current subgoal: place the second fruit on its matching plate (2/3)."
"Current subgoal: place the red block in the rightmost position."
```

工程细节：

- 官方 WLA 服务器支持 `obs["instruction"]` / `obs["task"]` 覆盖启动参数；不需要 fork 模型。
- 预先编码 94 个子目标 prompt，缓存文本 embedding；切换时只换 embedding，不重复 tokenization。
- 只在**子目标边界**切换，不在每个 chunk 切换；切换后的第一个 chunk 可与上一计划做短混合，避免动作跳变。
- 若 `P2` 与 `P0` 的动作方向余弦 < 阈值，回退 `P0`；prompt 调度不是无条件开启。

### 3.7 完成后 freeze + verify：保护最值钱的最后一步

25/32 个任务的最后一步值 40–50 分。完成后：

```text
VERIFY:
  hold 0.5–1.0 s
  re-check postconditions (b_last, target pose, stack/zip/lock state)
  if stable: DONE (hold position)
  if regressed: REPAIR last step
```

这既防止机器人自己继续动把成果碰坏，也防止人在最后一刻改动而模型没发现。

### 3.8 与 CHUNK-SERVO 的集成

- STATEKEEPER 决定“当前子目标 + 阶段提示 + 是否重做/冻结”。
- CHUNK-SERVO 决定“最后 3 厘米怎么闭环”：30 步 VLA 规划 + 5 步伺服执行。
- 两者在不同时间尺度：STATEKEEPER 在 chunk 边界（~167 ms）更新；CHUNK-SERVO 在 5 步块内修正。
- 目标检索库共用：STATEKEEPER 用阶段/对象检索，CHUNK-SERVO 用“目标-夹爪相对位姿”检索。
- 失败回退：STATEKEEPER 不确定 → 回退 CHUNK-SERVO/原 VLA；CHUNK-SERVO 不确定 → 回退原 VLA。层层 fail-open。

### 3.9 合规性

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | rubric/阶段标签只离线使用；线上只有 VLA | 最低 | 可用 |
| C2 确定性控制器 | FSM、证据融合、修复策略、TF-IDF 路由；无学习权重 | 低；需向官方说明 | **主推** |
| C3 同 checkpoint 特征 | 需要强描述子时，用同一 VLA encoder | 低–中 | 可选 |

禁止：加载第二个学习策略/残差网络/独立 VLM 裁判/独立视觉编码器做在线决策。

## 4. 创新点清单（本轮迭代版）

> 说明：每个点都按「动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险」写。清单不是 5 个独立大项目，而是 1 个主押注 + 4 个可单独验证的部件；每轮按 P0–P4 门裁剪。

### I1. RUBRIC-COMPILER：公开评分细则 → 94 状态任务契约

- **动机**：官方已公开 32 份 `info.json`、94 个评分步骤、每步分值；但参赛方案普遍只把任务名/整句指令当条件，没有显式利用“第几步、值多少分、后置条件是什么”。
- **与现有方案差异**：不是让 LLM 现编计划，也不是手工写 32 条轨迹；是把官方 rubric 编译成**数据驱动的契约**（JSON），FSM 只是解释器。
- **技术可行性**：高。32 份 JSON 已抓取；字段稳定；94 步、100 分/任务可直接校验。仅需 CPU。
- **所需资源**：1 人周；32 份 `tasks_v2/*/info.json`；HF `meta/tasks.parquet`；无需 GPU。
- **落地步骤**：抓取/校验 → schema → 32 任务编译 → 单元测试（步数/分值和=100/英文对齐）→ 版本化 `contracts.json`。
- **风险**：rubric 可能更新；中英文描述可能不完全对齐；过度依赖公开 rubric 可能被评测方调整。缓解：版本化 + 单任务通道复核 + 失败回退通用模板。

### I2. STATEKEEPER：非单调信念状态 + 局部修复（主押注）

- **动机**：15/32 任务含重复/计数；9/32 任务的 human 干扰会撤销已完成步骤；官方演示没有回退标注。单调开环策略在长程/计数/回退上系统性失分。
- **与现有方案差异**：不是第二个 VLA/世界模型；是确定性监督器。与 ActionGround 的通用四阶段 FSM 不同，我们用官方 94 步 rubric、RGB-only 证据、支持回退；与 Harness VLA/FLARE 不同，我们不引入 LLM/MLLM/新技能。
- **技术可行性**：中高。几何证据 + 演示检索 + 阶段时长先验都可离线验证；FSM 是 ~300 行解释器；94 个状态可管理。难点是后置条件观测（拉链/锁/折叠）——用检索 + 时序 + 不确定回退。
- **所需资源**：2–3 人周；CPU 16 核；33k 演示索引（<1 GB）；单任务通道；1 张 24GB GPU 跑 VLA。
- **落地步骤**：离线阶段分割 → 证据阈值标定 → 合成扰动回放 → 单任务 A/B → 全量干跑。
- **风险**：状态观测器误判 → 错误重做/提前切换；检索对未见物品/背景失效；额外延迟。缓解：高精度阈值、fail-open、按任务启用（P1 不过的任务不启用）、p99 预算。

### I3. BARGE-IN REPAIR：把人为干扰当作对话打断

- **动机**：human 轴占 20%；官方注记给出具体“撤销”场景；整任务重来浪费时间且可能碰坏已完成步骤。
- **与现有方案差异**：不是“检测到异常就 reset”；是撤回承诺 + 只重做受影响子目标；不是识别“人”，而是识别“场景变了且我的动作解释不了”。
- **技术可行性**：中高。可复用第 11 轮 GEO-RESIDUAL 的 edit_score；后置条件复查用同一套证据；修复动作是确定性策略。
- **所需资源**：1–2 人周；合成扰动数据；单任务通道；CPU。
- **落地步骤**：扰动目录（9 个任务）→ 检测阈值 → 修复策略 → T19/T27/T17/T16 单任务 A/B。
- **风险**：误报导致频繁暂停；漏报导致继续错；人把目标拿走时无法恢复。缓解：K 帧确认、最大重试、可见性检查、安全停止。

### I4. PHASE-PROMPT BUS：同一个 VLA 的阶段提示调度

- **动机**：一条固定指令覆盖 2–5 步；VLA 没有“当前子目标”的显式提示；官方 WLA 服务器支持 per-request instruction。
- **与现有方案差异**：不是再训一个 prompt-conditioned 模型；是推理期的“对话轮”调度；用原句+子目标句的 P2，降低分布漂移。
- **技术可行性**：中。需要验证 prompt 切换是否真的改善动作；可能无效甚至有害。官方服务器支持覆盖；文本 embedding 可缓存。
- **所需资源**：1–2 人周 + 1 GPU 周；VLA 推理；离线动作一致性测试；单任务通道。
- **落地步骤**：prompt 模板 → 离线动作散度测试 → P0/P1/P2 三档 A/B → 只在有效任务启用。
- **风险**：分布漂移/动作跳变/延迟；prompt 过拟合到 94 个模板。缓解：P2 保留原句、边界切换、散度回退、p99 监控。

### I5. PROTOTYPE-LADDER：先证伪，再烧 320 trials

- **动机**：320 trials 很贵；榜单是预览；前几轮容易把设计目标当结论。需要一个可证伪的阶梯。
- **与现有方案差异**：不是“先训大模型再真机”；是 P0 契约审计 → P1 离线回放 → P2 合成扰动 → P3 单任务 A/B → P4 全量干跑；每级有 kill criteria。
- **技术可行性**：高。已有单任务通道、33k 演示、官方 rubric；P0/P1 纯 CPU。
- **所需资源**：1 人周；CPU；单任务通道；可选 MuJoCo/IsaacLab。
- **落地步骤**：见 §5；每级记录指标和失败原因；不过门不提交。
- **风险**：单任务通道与正式评测分布不一致；5 个任务不能代表 32 个；评测噪声。缓解：配对 A/B、bootstrap、按任务分层、重复实验。

### 本轮剪枝（明确不做）

- **不做**从零训 VLA/World Model：官方 WLA 已开源 6B 基座，算力不划算。
- **不做**第二个学习状态分类器/第二个 VLM 裁判：单模型合规风险；用确定性证据。
- **不做**在官方演示上训“恢复策略”：没有失败/回退样本；用合成扰动 + FSM 修复。
- **不做**整任务 reset：局部修复更省时间、更安全。
- **不做**32 个任务各一个策略：规则禁止，且不泛化。
- **不做**把预览榜单当真实难度表：已证伪。
- **不做**30Hz 广域网伺服：RTT 不允许；沿用 5 步 chunk。
- **不做**力/触觉闭环：API 没有。
- **修正**“腕部无内参”：官方 `info.json` 明确有；G0 降级为标定误差问题。

- 从“任务名/整句指令”升级到“官方 94 步 rubric 契约”；
- 从“单调执行”升级到“非单调信念 + 局部修复”；
- 从“固定 prompt”升级到“阶段提示调度”；
- 从“仿真/真机混着做”升级到“P0–P4 阶梯，先证伪再烧 trials”。

**剪枝**：

- 不再把“腕部无内参”当风险（已修正）；
- 不再考虑第二个学习裁判/恢复策略；
- 不再从零训大模型；
- 不再整任务 reset；
- 不再把预览榜单当难度表。

## 7. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 状态观测器误判 | 错误重做/提前切换，反而降成功率 | 高精度阈值；fail-open；P1 不过的任务不启用 |
| 演示检索对未见物品/背景失效 | 阶段投票错误 | 用几何/时序兜底；只对刚体任务启用；低置信度回退 |
| Prompt 切换分布漂移 | 动作跳变/性能下降 | P2 保留原句；只在边界切换；散度回退 |
| 额外延迟 | p99 超标 | CPU 检索 <10ms；prompt embedding 缓存；只在转移点跑额外 VLA |
| 人为干扰误报/漏报 | 频繁暂停或继续错 | K 帧确认；多证据；最大重试；安全停止 |
| 单模型解释 | 被判定第二个模型 | FSM/路由/证据融合无学习权重；提交材料写清楚 |
| Rubric 变更 | 契约过期 | 版本化；单任务通道复核；通用模板回退 |
| 评测噪声 | 把 +1–2pp 的噪声当增益 | 配对 A/B；bootstrap；320 trials 非配对 SE≈2.6pp；不报小差异 |
| 过拟合 32 任务 | 泛化差 | 契约只描述任务骨架；不写死轨迹；按任务启用 |
| 超时 | 180s 上限 | 时间预算；局部修复；必要时保步骤分 |

## 8. 预期收益与成本（设计目标，不是承诺）

| 部件 | 影响面 | 假设增益 | 全局粗算 |
|---|---|---|---:|
| 重复/计数 FSM | 15 个任务 | +10pp | +4.7pp |
| 最后一步 freeze/verify | 8 个 close/zip/lock + 25 个最后一步≥40 | +10pp | +2.5pp |
| Barge-in 修复 | 9 个 undo 任务的 human 轴 | +20pp on human | +1.1pp |
| 阶段提示 | 10 个长程任务 | +5pp | +1.6pp |
| 重叠/回归折扣 | — | -50% | — |
| **合计** | — | — | **+4–5pp 保守；+6–8pp 乐观** |

这些是“如果 P1–P3 过门”的设计目标；不过门就不提交。320 trials 的全局非配对 SE≈2.6pp，任何小于 2pp 的差异都不应当作结论。

## 9. 三个灵感词怎么落到方案里

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **状态机** | RUBRIC-COMPILER → 94 状态分层 FSM；非单调信念；freeze/verify；局部修复 | 不写死轨迹；不做 32 个独立策略；不做第二个学习模型 |
| **原型验证** | P0 契约审计 → P1 离线回放 → P2 合成扰动 → P3 单任务 A/B → P4 全量干跑；每级 kill criteria | 不直接烧 320 trials；不把仿真成功率当结论；不把设计目标当结果 |
| **对话管理** | 意图路由（160 条同义指令）；阶段提示调度；barge-in 检测；承诺撤回；修复/确认；低置信度 clarification | 不做闲聊/语音；不假设 evaluator 会多轮对话（语言固定）；不引入 LLM 对话代理 |

## 10. 本轮的“一句话押注”

**把官方 32 项任务的 94 个评分步骤编译成一台可回退的非单调状态机，用几何 + 演示检索 + 同一 VLA 的动作一致性维护子目标信念，用阶段提示调度同一个 VLA，用对话式 barge-in 修复只重做被撤销的那一步——在不新增学习模型的前提下，把长程任务从「一次性开环」变成「可记忆、可回退、可局部重做」的监督执行。**

### 1.3 编译规则

1. **分值**：从 `scoring_points_en` 抽 `(\d+) pts`；若缺失用中文 `(\d+) 分`；每任务必须和为 100。
2. **步骤**：按换行/编号切分；每步保留英文原句（作为 `prompt` 的最小改写）与中文原句（给中文关键词路由）。
3. **对象/目标**：从英文句抽名词短语；`fruit 1/2/3` → `fruit[k]`；`all/remaining` → 区间；`plate with matching color` → `plate.color(fruit[k])`。
4. **顺序**：默认按 rubric 顺序；出现 `one by one/then/after` 时保留；`any` 仅在 rubric 明确不要求顺序时使用。
5. **后置条件**：优先用可观测几何/状态谓词；不可观测的（锁、拉链、折叠层数）用“检索阶段 + 时序 + 不确定回退”，不硬编码成功。
6. **标签**：`R`=编号/全量/剩余计数；`U`=官方 human 注记会撤销已完成步骤；`L`=终局 close/zip/lock；`H`=末步 ≥40 分。
7. **版本化**：`schema_version` + `source_sha256` + `fetched_at`；rubric 变更时 diff，不静默覆盖。

## 3. 非单调状态机：形式化规格

### 3.1 状态

对单个 episode、单个端口：

```text
q_t = (c_t, done_t, b_t, ℓ_t, retry_t, regress_t, phase_t, t0, last_a_t)
```

| 符号 | 含义 | 取值 |
|---|---|---|
| `c_t` | 当前子目标索引 | `1..N`（N=2..5） |
| `done_t[i]` | 是否已承诺完成 | `{0,1}` |
| `b_t[i]` | 完成信念 | `[0,1]` |
| `ℓ_t[i]` | 信念 logit | `R` |
| `retry_t[i]` | 重试次数 | `0..R_max` |
| `regress_t[i]` | 回退次数 | `0..R_ep` |
| `phase_t` | 执行阶段 | `EXEC / VERIFY / REPAIR / FREEZE / ABORT` |
| `t0` | episode 起始时间 | `monotonic` |
| `last_a_t` | 上一个 chunk | `(T_a, D)` |

### 3.2 证据函数

全部在 chunk 边界计算；`T_a=5` 时约 6 Hz。

| 证据 | 定义 | 取值 | 成本 |
|---|---|---|---|
| `g_i` | 几何后置条件：夹爪闭合于对象、对象随夹爪位移、对象进入目标 ROI、堆叠高度/重叠、拉链/盖子状态 | `[0,1]` | <1 ms |
| `r_i` | 演示检索：当前帧 top-k 最近邻中标签为步骤 i 的比例（softmax 加权） | `[0,1]` | 3–10 ms |
| `a_i` | 动作一致性：`cos(last_a, π(o, prompt_i)) - cos(last_a, π(o, prompt_{i+1}))`，再做 sigmoid | `[0,1]` | 2 次 VLA，仅在候选转移点 |
| `d_i` | 阶段时长先验：`exp(-((t-μ_i)/σ_i)^2)`，`μ,σ` 来自演示 | `[0,1]` | <1 ms |

**`a_i` 的用法**：只在 `b_i ∈ [0.4,0.7]` 的候选转移点计算；如果两个 prompt 产生的动作几乎一样（`|cos|` 高），说明 prompt 不具区分性，`a_i` 权重降到 0，避免噪声。

### 3.3 信念更新

```text
ℓ_i(t) = ℓ_i(t-1)
       + w_g · (2 g_i - 1)
       + w_r · (2 r_i - 1)
       + w_a · (2 a_i - 1) · 1[b_i ∈ [0.4,0.7]]
       + w_d · (2 d_i - 1)

b_i(t) = sigmoid(ℓ_i(t))
```

默认权重（离线标定，不是训练）：

```text
w_g = 1.2, w_r = 0.8, w_a = 0.6, w_d = 0.3
θ_done = 0.75, θ_regress = 0.35, θ_partial = 0.50, θ_edit = 0.60
K_reg = 3（连续 3 次低于 θ_regress 才回退）
```

### 3.4 转移函数

```text
EXEC:
  if b_c > θ_done and guard(c):        done[c]=1; c+=1; phase=VERIFY
  elif edit_score(o) > θ_edit:         phase=REPAIR
  elif t - step_start > budget(c):     phase=REPAIR

VERIFY / RECHECK（每 K 个 chunk，FREEZE 中也持续）:
  # 不是只查最近一步：9 个 undo 任务里，人可能撤销更早的步骤
  for i in done_indices(recheck=True):
      if b_i < θ_regress:
          streak[i] += 1
          if streak[i] >= K_reg and corroborated(i):
              done[i]=0; c=min(c,i); phase=REPAIR; break
      else:
          streak[i] = 0
  if no regression: phase = FREEZE if c >= N else EXEC

# corroborated(i) = (g_i < 0.2) or (至少两路证据同时 < 0.4)
# done_indices(recheck=True) = {i | done_i=1 且 step_i.recheck}

REPAIR:
  if b_c > θ_done:                     phase=EXEC
  elif retry[c] < R_max and visible(c):
      retry[c]+=1; phase=EXEC          # 用当前步骤 prompt 重试
  elif steps[c].independent:
      done[c]=0; c+=1; phase=EXEC      # 跳过独立步骤，保后续分
  else:
      phase=ABORT

FREEZE:
  hold(last_a)
  # 回退检测已由上面的 RECHECK 覆盖；这里只保持位姿
  else:                                keep FREEZE
```

### 3.5 非单调语义（与单调 FSM 的差别）

```text
单调 FSM：  done[i] = 1 之后永不改变；c 只增不减。
本 FSM：    done[i] 可被证据撤回；c 可回到 i；
            但回退必须满足：
            (1) b_i < θ_regress 连续 K_reg 次；
            (2) 证据不是单帧噪声（至少两路证据同向，或几何证据强）；
            (3) regress[i] < R_ep；
            (4) 回退后只重做 i，不 reset 整个任务。
```

**形式化不变量**：

1. `c ∈ [1,N]`；`c` 只在 `done[c-1]=1` 时前进（除非独立步骤跳过）。
2. `c` 只在 `phase=VERIFY/REPAIR` 且回退条件满足时后退。
3. `done` 的每次 0→1 或 1→0 都必须有证据记录；日志可审计。
4. `estimated_step_score = Σ_i points_i · done_i` 单调不减，除非发生回退；回退时记录扣分。
5. `FREEZE` 后不再输出新动作，除非回退条件满足。
6. 单 episode 的 `retry` 总和 ≤ `R_ep`；超限进入 `ABORT`，输出 hold。

### 3.6 安全与 fail-open

- `ABORT`：输出 hold（保持最后位姿），不做未知运动；记录失败码。
- `REPAIR` 前先 `hold 0.3–0.5 s`，避免人在工作区时继续动。
- `edit_score` 高且检测到人/手进入工作区：暂停，不重试。
- 任意模块异常：回退到“原句 + 原 VLA + 无 FSM”，保证不比基线更差。
- 时间预算：`t > 0.8×180s` 进入 `CONSERVE`，跳过独立低分步骤，优先完成当前高分步骤。

### 4.2 类与生命周期

```python
class StateKeeperPolicy:
    def __init__(self, vla, contracts, demo_index, router):
        self.vla = vla
        self.contracts = contracts          # 只读
        self.demo_index = demo_index        # 只读
        self.router = router                # 只读
        self.episode = 0
        self._new_episode()

    def _new_episode(self):
        self.episode += 1
        self.contract = None
        self.N = 0
        self.c = 0
        self.done = []
        self.logit = []
        self.belief = []
        self.retry = []
        self.regress = []
        self.regress_streak = []
        self.phase = "EXEC"
        self.t0 = time.monotonic()
        self.step_start = self.t0
        self.plan = None
        self.plan_prompt = None
        self.last_action = None
        self.recheck_at = 1
        self.events = []

    def reset(self):
        self._new_episode()

    def get_action(self, obs):
        now = time.monotonic()
        if self.contract is None:
            self.contract = self.router.resolve(
                obs["observation.language"], self.contracts)
            if self.contract is None:
                return self.vla.infer(obs, obs["observation.language"])
            self.N = len(self.contract["steps"])
            self.done = [0] * self.N
            self.logit = [0.0] * self.N
            self.belief = [0.5] * self.N
            self.retry = [0] * self.N
            self.regress = [0] * self.N
            self.regress_streak = [0] * self.N
            self.c = 0

        self._update_belief(obs, now)
        self._fsm_step(obs, now)

        if self.phase in ("FREEZE", "ABORT"):
            return self._hold_chunk()

        prompt = self._select_prompt(obs)
        chunk = self.vla.infer(obs, prompt)
        self.last_action = chunk
        self._log(obs, now, prompt, chunk)
        return chunk
```

### 4.3 信念 / FSM / 修复

```python
    def _update_belief(self, obs, now):
        idxs = {min(self.c, self.N - 1)}
        for i in range(self.N):
            if self.done[i] and self.contract["steps"][i].get("recheck", True):
                idxs.add(i)
        for i in sorted(idxs):
            g = self._geom(obs, i)
            r = self._retrieve(obs, i)
            d = self._duration(now, i)
            dlogit = 1.2 * (2*g - 1) + 0.8 * (2*r - 1) + 0.3 * (2*d - 1)
            if 0.4 <= self.belief[i] <= 0.7 and self.last_action is not None:
                a = self._action_consistency(obs, i)
                dlogit += 0.6 * (2*a - 1)
            self.logit[i] += dlogit
            self.belief[i] = sigmoid(self.logit[i])

    def _recheck_done(self, obs):
        # 检查所有已承诺完成的步骤，而不只是最近一步
        for i in range(self.N):
            if not self.done[i] or not self.contract["steps"][i].get("recheck", True):
                continue
            if self.belief[i] < 0.35:
                self.regress_streak[i] += 1
                if self.regress_streak[i] >= 3:
                    self.done[i] = 0
                    self.c = min(self.c, i)
                    self.regress[i] += 1
                    self.phase = "REPAIR"
                    return
            else:
                self.regress_streak[i] = 0

    def _fsm_step(self, obs, now):
        if self.c >= self.N and self.phase not in ("FREEZE", "REPAIR"):
            self.phase = "FREEZE"
        if self.phase in ("EXEC", "VERIFY", "FREEZE"):
            self._recheck_done(obs)
            if self.phase == "REPAIR":
                return
        if self.phase == "EXEC":
            if self.belief[self.c] > 0.75 and self._guard(obs, self.c):
                self.done[self.c] = 1
                self.c += 1
                self.step_start = now
                self.phase = "VERIFY" if self.c < self.N else "FREEZE"
            elif self._edit_score(obs) > 0.60 or self._timeout(now):
                self.phase = "REPAIR"
        elif self.phase == "VERIFY":
            self.phase = "FREEZE" if self.c >= self.N else "EXEC"
        elif self.phase == "REPAIR":
            if self.belief[self.c] > 0.75:
                self.phase = "EXEC"
            elif self.retry[self.c] < 2 and self._visible(obs, self.c):
                self.retry[self.c] += 1
                self.step_start = now
                self.phase = "EXEC"
            elif self.contract["steps"][self.c].get("independent", False):
                self.c += 1
                self.phase = "EXEC" if self.c < self.N else "FREEZE"
            else:
                self.phase = "ABORT"
        elif self.phase == "FREEZE":
            pass  # 保持位姿；上面的 _recheck_done 负责发现回退
```

### 4.4 阶段提示选择

```python
    def _select_prompt(self, obs):
        step = self.contract["steps"][self.c]
        orig = obs["observation.language"]
        p2 = f"{orig} Current subgoal: {step['prompt']}"
        if self.c > 0:
            p2 += f" ({self.c + 1}/{self.N})"
        return p2
```

**回退规则**：如果 `cos(π(o,p2), π(o,orig)) < 0.5`，说明 P2 与 P0 动作差异过大，改用 `orig`；该检查每 5 个 chunk 一次，避免频繁切换。

### 4.5 hold chunk

```python
    def _hold_chunk(self):
        # last_action 是 action dict；重复最后一帧，保持位姿（不发零力矩）
        out = {}
        for k, v in self.last_action.items():
            if k == "meta.token":
                out[k] = v
            else:
                out[k] = np.repeat(v[-1:], 5, axis=0)
        return out
```

### 4.6 每端口隔离

- 每个端口一个 `StateKeeperPolicy` 实例；`contracts`/`demo_index`/`router` 只读共享。
- `reset()` 清空所有 mutable 状态；不共享 `plan`/`last_action`/belief。
- VLA 服务器若共享，按端口 key 做 session；请求里带 `episode_id`，避免缓存串扰。

## 5. 阶段提示模板

### 5.1 三档

| 档 | 模板 | 用途 |
|---|---|---|
| P0 | `{orig}` | 基线；分布最稳 |
| P1 | `{step.prompt}` | 纯子目标；可能丢全局上下文 |
| P2 | `{orig} Current subgoal: {step.prompt} ({c+1}/{N})` | **默认**；保留全局 + 显式阶段 |

### 5.2 生成规则

- 94 个步骤各生成一条 P1；P2 = 原句 + P1 + 计数。
- 计数只在 `N>1` 时加；重复任务用 `(k/N)`，顺序任务用 `(red/green/yellow)` 或位置词。
- 不在 prompt 里写具体坐标/像素；避免过拟合到场景。
- 中文指令：保留中文原句，加中文子目标；不机翻成英文（避免二次误差）。

### 5.3 示例

```text
P2(T01,s1) = "Hang the cup on the marked spot on the cup rack. Current subgoal: Grab the cup handle. (1/2)"
P2(T04,s3) = "Sort the fruits into the plates with matching colors. Current subgoal: Place the last fruit on the plate with the matching color. (3/3)"
P2(T19,s2) = "Straighten the pouch and zip it up. Current subgoal: Zip up the pouch. (2/2)"
P2(T16,s5) = "Fold the towel and set it aside. Current subgoal: Fold and set it aside. (5/5)"
```

### 5.4 切换规则

- 只在子目标边界切换；同一子目标内不换 prompt。
- 切换后第一个 chunk 与上一 chunk 做 0.2 s 线性混合（若动作空间允许），降低跳变。
- 若 P2 与 P0 的动作余弦 <0.5，回退 P0；若连续 3 次回退，该任务禁用 prompt 调度。
- 记录每次切换的 `c`、`b_c`、`cos`、延迟，供 P3 分析。

## 7. 原型验证阶梯 P1–P4（待跑）

### 7.1 P1：33k 演示离线回放（CPU，0 真机）

**目的**：验证 FSM 在干净演示轨迹上不误回退、能到 DONE；验证反向回放能触发回退。

**协议**：

1. 按 episode 划分 train/val（不按帧），val 取每任务 10%（约 3,300 episodes）。
2. 对每个 val episode，按 30 fps 前向跑 belief/FSM（可用真值时间轴初始化 `d_i`，但不使用真值阶段标签）。
3. **前向测试**：记录是否到达 `FREEZE`；最终 `done` 是否全 1；误回退次数；每步切换点与演示动作事件（夹爪开合/物体位移）是否对齐。
4. **反向测试**：在每个步骤边界后，取该 episode 的 `k..k-Δ` 帧逆序回放（模拟“人把步骤改回去”），检查 `b_i` 是否在 ≤3 个 chunk 内低于 `θ_regress`，并触发 `REPAIR`。
5. **阈值扫描**：`θ_done ∈ {0.65,0.70,0.75,0.80}`，`θ_regress ∈ {0.25,0.30,0.35,0.40}`；选前向误报 ≤5%、反向检出 ≥90% 的工作点。

**指标与通过标准**：

| 指标 | 通过标准 |
|---|---|
| 前向到达 DONE | ≥90% val episodes |
| 前向误回退 | ≤5% episodes |
| 反向回退检出 | ≥90% 注入点，≤3 chunks |
| 步骤切换点误差 | 中位数 ≤0.5 s（15 帧） |
| CPU 延迟 | p99 ≤10 ms/次 |

**失败动作**：若前向误回退 >10%，只保留 `g_i`（几何）+ `d_i`（时长），关闭检索/动作证据；若反向检出 <70%，P2 只做检测告警，不做自动修复。

**诚实边界**：反向回放测试的是“信念更新对观测序列逆转的反应”，不是物理上的人为干扰；后者留给 P2。

### 7.2 P2：合成 barge-in（仿真/低速真机，9 任务）

**目的**：验证“检测→暂停→重定位→局部修复”的闭环。

**9 个任务与扰动**（来自官方 human 注记）：

| 任务 | 扰动 | 注入时机 | 期望回退到 |
|---|---|---|---|
| T10 PlugCharger | 拔起插头 | 插入后 | s3 |
| T14 PourOutMedicine | 拧回盖子 | 开盖后 | s1 |
| T16 FoldTowel | 翻开毛巾 | 折好后 | s5（或 s2–s4） |
| T17 OrganizeStationery | 打开笔盒 | 合盖后 | s5 |
| T19 ZipUp | 拉开拉链 | 拉上后 | s2 |
| T24 ConveyorSorting | 放回传送带起点 | 抓取/放置后 | s1/s2 |
| T26 PlugInEthernet | 移开网线/插口 | 插入后 | s3 |
| T27 StackBowls | 拿下第二个碗 | 叠第二个后 | s2 |
| T29 PackPhone | 移开外壳盖 | 合盖后 | s3 |

**协议**：

1. 仿真（优先）：在 MuJoCo/IsaacLab 里重放演示轨迹，脚本在注入时机执行扰动；记录 RGB/本体。
2. 真机低速（备选）：单任务通道，机器人低速；人按脚本扰动；安全员在场。
3. 每个任务 ×3 次 ×2 条件（有/无 STATEKEEPER）；共 54 次（仿真）或 54 次低速真机。
4. 记录检测延迟（扰动后到 `phase=REPAIR`）、修复动作、最终步骤分、误报、碰撞/人安全事件。

**指标与通过标准**：

| 指标 | 通过标准 |
|---|---|
| 检测延迟 | 中位数 ≤300 ms，p95 ≤600 ms |
| 修复成功率 | ≥60%（回到被撤销步骤并完成） |
| 误报率 | ≤10% episodes |
| 完成时间 | 修复后 ≤1.5× 原步骤时长 |
| 安全事件 | 0 |

**失败动作**：检测过慢→只做 freeze（不自动修复）；误报高→提高 K_reg/θ_edit；修复成功率低→只重做当前步，不跨步回退。

### 7.3 P3：单任务 A/B（真机，5 任务 ×2 臂 ×5 次）

**目的**：在不动正式 320 trials 的前提下，看 STATEKEEPER 是否在真机上涨点。

**任务选择**（覆盖 2/2/3/4/5 步、R/U/L/H）：

| 任务 | 步数 | 关键能力 | 为什么选 |
|---|---:|---|---|
| T01 HangCup | 2 | 抓取 + 悬挂 + 50 分末步 | 最短、最快看 freeze |
| T19 ZipUp | 2 | 拉链 + undo | 终局 + 人为拉开 |
| T27 StackBowls | 3 | 重复 + undo | 计数 + 拿碗 |
| T09 ToolboxStorage | 4 | all/remaining + lock | 全量 + 锁 |
| T16 FoldTowel | 5 | 多步折叠 + undo | 最长、最易状态混叠 |

**设计**：

- 2 臂：`A0`=原句 + 原 VLA + 无 FSM；`A1`=STATEKEEPER（P2 + FSM + barge-in + freeze）。
- 每任务每臂 5 次，共 50 次；同一初始物体位置（标定后复现）；随机化臂顺序。
- 单任务通道不计分；若允许，重复 2 轮（共 100 次）以提高功效；不允许则 5 次只当方向性。
- 不用正式 10 次/任务额度。

**指标**：

| 指标 | 说明 |
|---|---|
| 成功率 | 主指标 |
| 步骤分 | 官方 rubric 估计 |
| 完成时间 | 180 s 内 |
| 回退检测/修复次数 | 日志 |
| 误修复 | 无扰动时触发 REPAIR 的次数 |
| p99 延迟 | `get_action` 端到端 |
| 人工干预 | 安全员介入次数 |

**分析**：

- 配对差值（同任务/同初始位置）优先；bootstrap 10k 次，报告 95% CI。
- 5 次/臂的 Wilson 区间很宽（0–5 次成功 → 0–52%），所以只看“≥3/5 任务同向 +10pp”，不宣称显著。
- 若 2 轮可用，合并 10 次/臂；仍按任务分层，不把 50 次当独立样本。

**通过标准**：≥3/5 任务 +10pp；无任务回归 >5pp；p99 ≤150 ms（不含 VLA 推理）或 ≤VLA 基线 +20%；0 安全事件。

### 7.4 P4：N 端口全量干跑（mock evaluator / 仿真）

**目的**：验证工程契约，不验证成功率。

**协议**：

1. 起 N 个端口（8765..8765+N-1），每个端口独立 policy 实例。
2. 用 mock evaluator 按官方 obs/action schema 发 32 任务 ×1 次 ×N 端口。
3. 检查：reset 隔离、action shape/dtype、token、chunk 长度、内存、延迟、异常恢复。
4. 人为注入：断连、慢请求、重复 reset、乱序请求、空图、语言缺失。

**通过标准**：

| 检查 | 标准 |
|---|---|
| 端口串扰 | 0（belief/plan 不共享） |
| reset 干净 | 新 episode 的 `c=0, done=0` |
| action schema | 0 错误 |
| 内存 | 1,000 episodes 后增长 <5% |
| 延迟 | p99 ≤150 ms（CPU 部分） |
| 异常恢复 | 100% fallback 到 hold/原 VLA，不崩溃 |

### 7.5 正式 320 trials 的门

只有 P0–P4 全部通过才动正式评测：

```text
P0 全过
P1 前向 DONE ≥90%，误回退 ≤5%，反向检出 ≥90%
P2 检测 ≤300ms，修复 ≥60%，误报 ≤10%
P3 ≥3/5 任务 +10pp，无任务 -5pp
P4 0 串扰，0 schema 错误，p99 ≤150ms
```

任何一门不过：不提交 STATEKEEPER 版本；保留基线或只提交已通过的子集（例如只加 freeze，不加 barge-in）。

### 9.1 日志 schema（每 chunk 一条）

```jsonc
{
  "episode_id": "port0-T19-0003",
  "task_id": "T19",
  "port": 0,
  "trial": 3,
  "t": 12.35,

  "c": 1,

  "belief": [0.91, 0.22],
```

### 9.2 失败分类

| 码 | 类别 | 例子 | 处理 |
|---|---|---|---|
| F1 | 感知 | 物体未检出/位姿错 | 重定位；切换腕部视角 |
| F2 | 抓取 | 滑脱/夹空 | 重试；调整夹爪 |
| F3 | 运输 | 碰撞/掉落 | 回退；保守增益 |
| F4 | 放置 | 未对准 | 伺服；重试 |
| F5 | 状态 | 步错/计数错 | FSM 回退；重查 |
| F6 | 回退 | 人撤销未检出 | 提高证据；freeze |
| F7 | 修复 | 重做错步/碰坏 | 限制重试；安全停止 |
| F8 | Prompt | 动作漂移 | 回退 P0；禁用调度 |
| F9 | 超时 | 180 s | CONSERVE |
| F10 | API | schema/延迟 | fallback/hold |
| F11 | 安全 | 人进入工作区 | 暂停 |

### 9.3 分析计划

- 每任务报告成功率、步骤分、失败码分布；不只报总平均。
- 对 P3 的 5 个任务做配对分析；对 P2 的 9 个任务做检测延迟分布。
- 失败案例逐条回放：`belief` 轨迹 + 证据 + 动作；标注是“证据错”还是“策略错”。
- 每周更新一次失败码计数；连续两周同一码 >30% 则优先修。

### 11.2 单模型声明（建议措辞）

## 13. 待验证问题（按优先级）

1. **控制频率与 RTT**：评测端实际多少 Hz？`get_action` 往返多少 ms？→ 用一个只返回 hold 的 ping policy 在单任务通道测 100 次，记录时间戳。
2. **chunk 执行语义**：evaluator 是否一定执行完整 chunk 才再调用？→ 在 `get_action` 里打印时间戳/动作 index，观察调用间隔。
3. **human 轴注记**：9 个 undo 注记是 2 次 human trials 都执行，还是只执行其一？→ 问官方/看手册；P2 覆盖两种。
4. **rubric 稳定性**：`tasks_v2/*/info.json` 是否会在评测前变？→ 每周 diff；契约版本化。
5. **腕部内参精度**：官方 `camera_matrix` 是否与实际安装一致？→ 用已知尺寸棋盘格/物体做 10 次重投影误差测量；目标 <3 px。
6. **评测语言**：用 160 条同义指令之一，还是新改写？→ 无法预知；路由器必须支持回退；P3 用同义指令和新改写各测。
7. **动作空间**：EE 还是 joint 对 WLA 更稳？→ P3 前用单任务通道各跑 10 次。
8. **提交次数限制**：每天/总共几次？→ 问官方；在拿到答复前不动正式额度。
9. **单模型解释**：确定性 FSM + 检索是否被接受？→ 提交前问官方；材料写清楚；备选是只提交 VLA + prompt，不带 FSM。
10. **单任务通道限制**：能否 5 次/臂？→ 问官方；不行则降到 3 次/臂，只做方向性判断。
11. **p99 延迟预算**：VLA 基线 p99 多少？→ 先测基线，再定 STATEKEEPER 的 CPU 预算（建议 ≤基线 20%）。
12. **内存**：33k 演示检索索引多大？→ 先做 1/10 子集，测 RAM/查询延迟；目标 <1 GB、<10 ms。
