## 0. 本轮结论

这一轮先做了四件“扫雷”：

1. **规则**（Feishu 手册 1.1–2.2，2026-10-23）：仅通才模型赛道；**单模型完成全部 32 任务，不得混合多个模型**；每任务 **10 次**，5 类泛化各 2 次；单次 ≤180s；排名按 **总平均成功率 → 总平均步骤分 → 提交日期**；自部署；N 端口 `8765…8765+N−1`；单任务调试不计分。
2. **榜单仍是占位**：`leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`；`details.html` 写“测试视频占位”；`runs.html` 是 256/256 + “即将发布”。8 条分数不能当证据。
3. **接口差异（本轮新增，P0）**：评测 obs **不发送** `state_torso`/`state_d435`/`waist_state_joint`；评测 action **只收** `pivot[7]` + 双臂（joint 7 或 EE 6）+ 双 gripper，**不收** `lower_body`/`base_command`/`action_torso`/`action_d435`/legs。WLA-1.0 的 Dex1 配置又恰好用 `waist_action_joint`/`base_command`/legs，不直接用 `pivot`；EE 动作还是相对量，而挑战 API 要 base 系绝对位姿。**不先做接口对齐，离线指标会骗人。**
4. **数据是 success-only**：32 任务/约 33k episodes/169h/4 路 RGB/30fps/LeRobot v3.0/Apache-2.0；没有 force/tactile/depth 标签，也没有失败、恢复、人为撤销、接触力标签。官方评测却专门考这四类。

主判断：

> **上一轮把主押注放在 SPA-VLA + RPSM；这一轮发现更底层的瓶颈是 state coverage（状态覆盖）。** 官方 32k 是成功轨迹；评测不给 depth/force，且不发送部分 proprio，又用 5 类泛化和撤销式干扰把机器人推出成功分布。模型再大，也是在补它没见过的状态。RUBICON 4.0 = **State-Coverage Flywheel（SCF）**。

SCF 的五个部件：

- **OCB（Open-hardware Counterfactual Bench）**：用 SO-101 干扰臂、HandUMI/UMI-FT、AprilTag、F/T、G1 夹爪适配件搭一个**离线**反事实测试/采集台；不改评测机器人。
- **CSCE（Counterfactual State-Coverage Engine）**：失败优先采集 + 主动选择，补 failure/recovery/contact/unseen/background 五类状态；目标 3–5k episodes，不是再采 32k 成功演示。
- **FBS（Factored Belief State）**：物体/部件 6D pose + articulation + contact/force + 关系 + 任务阶段 + 不确定性；作为**单模型 VLA 的辅助头 + 确定性滤波器**，部署仍是一个 checkpoint。
- **IPT + CPSC（Interface-Parity Training + Camera Pose Self-Calibration）**：训练/评测同分布；缺失键 dropout；动作空间掩码；相对→绝对 EE 桥；头部外参自标定。
- **SARP + HIM + CD（State-Aware Recovery Policy + Human Interference Monitor + Contact Distillation）**：撤销检测、最小子目标修复、人手接近/遮挡监测、无传感器接触估计。

一句话：**不是再训一个更大的 VLA，而是用开源硬件把 success-only 数据变成 failure/recovery/contact 的状态覆盖，再把这套覆盖蒸馏成单模型内部的可微 belief state；接口对齐优先于模型规模。**

## 1. 本轮新增/修正事实

### 1.1 规则（已读 1.1–2.2；其余未核实）

| 项 | 已核实内容 | 影响 |
|---|---|---|
| 赛道 | 仅通才模型；单模型完成 32 任务，不得混合多个模型 | FBS/HIM 必须是同一 checkpoint 的辅助头；OCB 只离线 |

### 1.3 接口差异（P0，本轮最重要的工程发现）

| 信号 | 数据集（`info.json`） | 评测 API（README §2/§3） | 差异/动作 |
|---|---|---|---|
| 头部相机 | `head_stereo_left/right`，480×640×3，30fps，AV1；`camera_params` 有双目内参/外参，`rectified: true` | `cam_left_high`/`cam_right_high`，480×640×3 uint8 | 改名；是否矫正/同内外参未知；IPT 做随机裁剪/缩放/矫正增广；CPSC 估外参 |
| 腕部相机 | `wrist_left/right` | `cam_left_wrist`/`cam_right_wrist` | 改名；分辨率可 resize |
| 双臂关节 | `left_arm`/`right_arm` 7 | 同 | OK |
| EE pose | `left/right_ee_pose_gripper_base` 6 + torso 6 | base 6 | 只用 base；torso 用 FK 推 |
| gripper | 1+1 | 1+1 | OK |
| lower body | `lower_body` 15；另有 legs 6+6、waist 3 | `lower_body` 15 | 可切片出 waist/legs；不要声明不存在的键 |
| torso | `state_torso` 6 | **无** | 缺失；用 waist/URDF FK 或 belief 推 |
| D435 | `state_d435` 6 | **无** | 缺失；CPSC/头部外参估计；训练时蒸馏 |
| waist | `waist_state_joint` 3 | **无独立键**（在 `lower_body` 内） | 切片；不要单独声明 |
| 深度 | 只有双目 RGB；无 depth | 无 depth | 立体匹配/单目深度头；或纯 RGB |
| force/tactile | 无 | 无 | CD 从 RGB+proprio 蒸馏；F/T 只在 OCB |
| 动作 | arms/grippers/lower_body/legs/waist/EE/torso/d435/base_command/pivot/gripper_controls | 仅 `pivot[7]` + arms（joint 7 或 EE 6）+ grippers | 动作掩码；丢掉数据集多余槽；`pivot` 单独头 |
| EE 语义 | 数据集有 base/torso 两套 EE；WLA 用相对动作 | **base 系绝对** `xyz+rpy` | 相对→绝对：`T_target = T_current @ T_rel`；再转 rpy |
| WLA 配置 | `action.waist_action_joint` + `base_command` + legs；无 `pivot` | 只收 `pivot` | 新增 pivot 槽/头，或从 waist/base/legs 学映射；不要直接套 WLA server |
| task id | `task_index` | 无 task id，只有 `observation.language` | 不用 task id；语言+图像+proprio；语言复述增广 |
| chunk | 数据集 30fps；WLA chunk 30 | `action_chunk_size` 任意 ≥1；示例 8 | 延迟预算；p99 < 0.8×chunk |

**结论**：这不是“改几个 key”的问题，而是**观测支持集、动作语义、动作空间、相机标定**四件事同时漂移。IPT/CPSC 必须是 P0，先于任何大模型训练。

### 1.4 数据集解剖

- 规模：官方页 32 任务/32000 episodes/169h；HF 逐任务合计约 **33,276 episodes**（ColorArrangement 1533 是 outlier）。
- 格式：LeRobot v3.0；Apache-2.0；30fps；4 路 RGB（480×640×3，AV1）；每任务 5 条英文语言复述。
- state：双臂 7+7、grippers 1+1、`lower_body[15]`、`left/right_leg[6]`、EE base/torso 6+6、`state_torso[6]`、`state_d435[6]`、`waist_state_joint[3]`、`recomputed_ee_valid[1]`。
- action：双臂 7+7、grippers 1+1、`lower_body[15]`、`pivot[7]`、`gripper_controls[4]`、legs 6+6、`base_command[4]`、EE base/torso 6+6、`action_torso[6]`、`action_d435[6]`、`waist_action_joint[3]`。
- 标签缺口：**无 force/tactile/depth**；无 failure/recovery/undo 标签；无部件级 pose/contact 标签；success-only。
- 标定：每任务 `camera_params` 不同（fx 约 186–296；baseline 约 46.7–64.9mm；cx 左右不同）；头部有运动，不能全局硬套外参。
- 结论：官方数据足够学“成功怎么走”，不够学“失败怎么修”；CSCE 补的是后者。

## 2. 三条灵感词的落点

### 2.1 数据采集 → CSCE

- 官方数据是 success-only；评测的 5 类泛化和人为撤销把机器人推出成功分布。
- 采“失败”不是采“更多成功”：每个任务采成功、失败、失败后恢复、被撤销后恢复、接触/对齐、未见物、背景变化。
- 目标 3–5k episodes（30–50h），按任务边际收益分配；先 5 个接触/撤销任务，再 15，再 32。
- 主动选择：`score = α·coverage + β·uncertainty − γ·cost`；子模贪心；每轮用 FBS 的失败/不确定度挑下一批。
- 不是“数据越多越好”：success-only 的 32k 已经够多；缺的是**反事实状态**。

### 2.2 状态估计 → FBS

- 评测不给 depth/force/`state_d435`/`state_torso`；靠 RGB+proprio 估。
- FBS 把状态拆成：物体/部件 6D pose、articulation、contact/force、关系（on/in/stacked/inserted/held）、phase、uncertainty。
- 作为单模型 VLA 的辅助头；用确定性滤波器（EKF/UKF/离散 Bayes/粒子）跨帧融合；不引入第二个 learned model。
- 好处：接触可检查、进度可回退、恢复可定位、主动感知有目标、失败可解释。
- 与 BEACON/LM-X/SAVE 的区别：它们做 belief/progress/uncertainty 的一部分；FBS 把**部件级几何 + 接触 + 关系 + phase + uncertainty**统一成一个可微接口，且用 OCB 的 F/T/AprilTag 标签训练。

### 2.3 开源硬件 → OCB

- 官方 G1 贵/稀缺；SO-101/HandUMI/UMI-FT 便宜、可并行、安全，适合采接触/失败/力。
- SO-101 做干扰臂：可重复地撤销/移除/遮挡/移动物体；HandUMI 做无机器人采集；UMI-FT/6-axis F/T 给力标签；AprilTag 给 6D pose 标签；G1 夹爪适配件保证 embodiment 对齐。
- OCB 只在离线用；不改评测机器人、不加传感器、不做任务硬编码。
- 成本约 $3–5k；2–3 周可出 3–5k episodes；比在 G1 上盲采便宜一个量级。

### P0-1 OCB + CSCE（数据引擎）

- **动机**：success-only 不覆盖评测的 failure/recovery/contact/unseen/background；多采成功演示边际收益递减。
- **与现有方案差异**：不是“再采 32k”，而是 3–5k 反事实状态；不是“仿真 RL”，而是真实开源硬件；不是“评测时加传感器”，而是离线标签 + 蒸馏。
- **可行性**：SO-101/HandUMI/UMI-FT 成熟；xr_teleoperate/LeRobot 可直接用；AprilTag/F-T 提供自动标签；G1 适配件解决 embodiment。
- **资源**：$3–5k 硬件；2 名操作员；1 台 G1 或 SO-101；30–50h 采集；2–3 周。
- **步骤**：W1 搭 OCB MVP；W2 在 5 个任务采 500 episodes；W3 标签+训练；W5 扩到 15 任务/2k；W6 视收益扩到 32。
- **风险**：规则禁止外部数据 → OCB 只做评测/标签，训练用官方数据自监督；数据质量 → 双人复核/自动门禁；sim2real → 域随机化 + 真实 OCB。

### P0-2 IPT + CPSC（接口对齐）

- **动机**：训练/评测的 obs 支持集、动作空间、EE 语义、相机名/内外参都不一致；不修就是“离线 60%、线上 0%”。
- **与现有方案差异**：不是简单 rename；是观测 dropout、动作掩码、相对→绝对、pivot 槽、相机自标定的完整 parity 层；有单元测试。
- **可行性**：纯工程，1–2 周；不改模型结构；用官方数据 + eval stub 即可测。
- **资源**：1 名工程师；eval harness；URDF/`camera_params`。
- **步骤**：W1 建 parity loader + stub；单测 32 任务；跑 B0/B1 对比；CPSC 用 `state_d435` 蒸馏 + URDF FK；W2 固化。
- **风险**：评测相机内外参未知 → 用统一 resize/裁剪 + 自标定 + 鲁棒编码器；缺失 torso → FK/学习推断；pivot 语义未知 → 安全探针（小步、限幅）。

### P0-3 FBS（状态估计）

- **动机**：评测缺 depth/force/部分 proprio；接触/对齐/撤销需要状态，不是单帧映射。
- **与现有方案差异**：不是外挂感知模型；是同一 checkpoint 的辅助头 + 确定性滤波；不是物体级 bbox，而是部件级 pose/contact/relation/phase/uncertainty。
- **可行性**：WLA/π0.5 可加头；6D pose/分割教师成熟；EKF/UKF 成熟；OCB 有标签。
- **资源**：GPU 训练；AprilTag/F-T 标签；1–2 人 3–4 周。
- **步骤**：W1 schema；W2 头+滤波；W3 训练/蒸馏；W4 集成/消融；W5 扩任务。
- **风险**：pose 精度不足 → 只用 contact/phase/relation，最后毫米靠腕部伺服；标签噪声 → 校准/一致性；延迟 → 小头+2ms 滤波。

### P0-4 SARP（撤销恢复）

- **动机**：官方 `human_1`/`human_4` 是撤销/移除/重置，不是“手挡一下”；进度不能单调。
- **与现有方案差异**：不是从头重跑；用 FBS 检测“哪个子目标被回退”，只修复最小子目标；HIM 决定等待/后退。
- **可行性**：官方备注给出 10 个撤销任务；OCB 可脚本化复现；规则式/学习式策略都可。
- **资源**：OCB 撤销集；1 人 2 周。
- **步骤**：W2 建 undo 测试集；W4 训练/规则；W5 集成；W6 全任务。
- **风险**：人手意图难测 → 保守等待 + 安全距离；过拟合脚本 → 随机化时序/位置；规则不允许“人工干预检测” → 只用视觉状态回退，不显式识别人手。

## A. 执行摘要

**问题**：UniBot-V1 要求一个模型完成 32 项 G1 桌面任务，每任务 10 次、5 类泛化。官方 32k 演示是 success-only；评测不给 depth/force，也不发送 `state_d435`、`state_torso`、`waist_state_joint`，并且动作端只接受 `pivot[7]` + 双臂 + 双 gripper。模型再大，也会在“没见过的状态”和“训练/评测接口不一致”上翻车。

**洞察**：本轮把瓶颈从“模型容量”改成 **state coverage（状态覆盖）**。官方数据覆盖“成功怎么走”，不覆盖“失败怎么修、接触最后几毫米、被人撤销后怎么恢复”。同时，WLA-1.0 等开源底座的训练接口与挑战 API 并不一致：观测键、动作槽、EE 相对/绝对语义、相机名/内外参都不同。**不先做接口对齐，离线指标会系统性高估。**

**方案**：RUBICON 4.0 / State-Coverage Flywheel（SCF）。

1. **OCB**：用 SO-101 干扰臂、HandUMI/UMI-FT、AprilTag、F/T、G1 夹爪适配件搭离线反事实采集/测试台；不改评测机器人。
2. **CSCE**：失败优先 + 主动选择，采 3–5k episodes，补 failure/recovery/contact/unseen/background。
3. **FBS**：在单模型 VLA 内加物体/部件 6D pose、articulation、contact/force、关系、phase、uncertainty 辅助头 + 确定性滤波。
4. **IPT/CPSC**：观测 dropout、动作掩码、相对→绝对 EE 桥、pivot 槽、相机自标定。
5. **SARP/HIM/CD**：撤销检测与最小子目标修复、人手接近/遮挡监测、无传感器接触蒸馏。

**预期收益**（目标，不是承诺）：总平均成功率 +3pp；接触类任务 +10pp；撤销恢复 +15pp；数据成本比在 G1 上盲采低一个量级（3–5k episodes，$3–5k 硬件，30–50h 采集）。

**成本**：硬件约 $3–5k；算力约 $10–15k（或自有集群）；2–3 人 8 周；数据 30–50h。不含 G1 本体。

**Go/No-Go**：FBS pose <1cm/5°、contact F1 >0.9；B3 相对 B1 总成功率 +3pp、接触任务 +10pp、恢复 +15pp；p99 延迟 <0.8×chunk。达不到就降级到“IPT/CPSC + Portfolio + SPA-VLA”的安全提交。

**不做什么**：从零训练大模型、14B world model、完整仿真 RL、改评测机器人硬件、任务硬编码、在线 LLM/VLM API、只堆成功演示、追 1pp 榜单噪声。

### B.3 统计功效与目标

- 总试验数：32 任务 × 10 次 = **320**。
- 若 p≈0.3：`SE = sqrt(0.3×0.7/320) ≈ 2.56pp`；95% CI ≈ **±5.0pp**。
- 单任务 10 次：`SE ≈ 14.5pp`；95% CI ≈ ±28.4pp。**任务级噪声极大**，必须看跨任务聚合/配对，不要用单任务 1–2 次涨跌做决策。
- 目标 +3pp：相当于 320 次里多 9.6 次成功；例如 3 个任务各 +32pp，或 5 个任务各 +19pp。
- 边际收益：
  - 一个任务 +10pp → 总平均 +0.31pp。
  - 5 个 0% 任务提到 30% → 总平均 +4.7pp。
  - 因此**先消灭 0% 任务**，再攻高杠杆接触/撤销任务。
- Beta-Binomial：任务 i 的后验 `p_i ~ Beta(α0+s_i, β0+f_i)`；用后验均值/95% 区间排序；按“提升总平均的边际收益/成本”分配调试预算。
- 不做“单次 320 trials 的 3pp 显著性”承诺；用 3 seeds、任务配对、bootstrap CI。

### C.2 六个语义差异（不是简单改名）

1. **观测支持集变窄**：评测缺 `state_torso`、`state_d435`、`waist_state_joint`；只给 `lower_body[15]`。训练时如果把这三类当输入，部署时就会缺输入。
2. **动作空间变窄**：评测只收 `pivot[7]` + 双臂（joint 7 / EE 6）+ 双 gripper；数据集里的 `lower_body`、`legs`、`waist_action_joint`、`action_torso`、`action_d435`、`base_command`、`gripper_controls` 都不收。训练必须做动作掩码，不能把整个 54D/60D 直接吐给评测。
3. **EE 语义是绝对，不是相对**：README 写“Target ... pose in base frame: xyz(3)+rpy(3)”；WLA-1.0 的 action expert 预测**相对** EE pose，再由 adapter `T_abs = T_curr @ T_rel` 组合。部署到挑战 API 时必须自己做组合 + 转 rpy，否则会把“相对小位移”当成“绝对坐标”。按 README 字面是绝对；上线前用零动作/小步探针确认，桥保留 relative/absolute 开关。
4. **WLA-1.0 的 Dex1 配置不含 `pivot`**：`unitree.yaml` 的 `unitree_base` 用 `action.waist_action_joint` + `action.base_command` + `action.left_leg/right_leg`；挑战 API 只收 `pivot[7]`。两条路：
   - 在 action layout 中新增 `pivot` 槽，用数据集 `action.pivot` 直接监督；
   - 或学一个 `(waist[3], base_command[4]) → pivot[7]` 的桥，再用挑战数据校准。
   不要直接套 WLA 的 `action_server_wbc_msgpack_unitree.py`；它的 `_encode_action` 只覆盖 Dex1 的 WBC 动作空间。
5. **相机名/分辨率/矫正未知**：数据集头部是 rectified stereo（`camera_params` 有 `R/T/fx/fy/cx/cy`，每任务不同）；评测 `cam_left_high/right_high` 是否同一对、是否矫正、内外参是否一致都未核实。训练要做随机 resize/crop/矫正/颜色增广，并做 CPSC。
6. **没有 task id，只有语言**：评测只给 `observation.language` 一条字符串；数据集有 `task_index` 和 5 条复述。不要用 task id 做 one-hot；用语言 + 图像 + proprio，并在 5 条复述上做留一法。

### C.3 IPT：Interface-Parity Training

**目标**：训练时的输入/输出分布尽可能等于评测时的输入/输出分布。

**数据侧**：

- 统一键名：`head_stereo_left→cam_left_high`、`head_stereo_right→cam_right_high`、`wrist_left→cam_left_wrist`、`wrist_right→cam_right_wrist`。
- 只保留评测可用的观测：`left_arm`、`right_arm`、`left_ee_pose_gripper_base`、`right_ee_pose_gripper_base`、`left_gripper`、`right_gripper`、`lower_body`、4 路图像、language。
- `state_torso`/`state_d435`/`waist_state_joint` 只作为**训练辅助标签/蒸馏目标**，不作为部署输入；训练时随机 dropout，模拟部署缺失。
- `lower_body[15]` 按固定布局切片出 waist（3）+ legs（12）；如果评测布局不同，做一致性检查。
- 动作：只保留 `pivot[7]`、`arms[7+7]`（joint）或 `EE[6+6]`（ee）、`grippers[1+1]`；其余维度只做辅助 loss 或直接 mask。
- 图像：随机 resize 到 240×320 / 224×224 / 原图；随机 crop/color jitter/模糊/压缩；模拟评测的 uint8、不同曝光。
- 语言：5 条复述 + 同义改写 + 留一法；不要让模型记住某一条字符串。
- 时间：随机丢帧/重复帧/不同 chunk 起点；模拟评测的 `obs_delta_indices` 堆叠。

**模型侧**：

- **Observation dropout**：训练时以 p=0.1–0.3 随机丢掉 `state_d435`/`state_torso`/`waist`/一路相机/一条手臂历史；强制模型从剩余模态推断。
- **Action mask**：loss 只在评测接受的维度上计算；辅助维度用低权重（可选），部署时丢弃。
- **EE 绝对桥**：`T_target = T_current @ T_rel`；`xyz = T_target[:3,3]`；`rpy = R_to_euler(T_target[:3,:3], "xyz")`；工作空间 clamp + 速度限幅。
- **Pivot 头**：新增 7D 槽；用 `action.pivot` 监督；如果 pivot 语义不确定，先输出 0/小步，做安全探针。
- **Chunk**：训练 chunk 30；部署可选 8–30；receding horizon；p99 延迟预算。
- **双控制空间**：joint 模式输出绝对关节；ee 模式输出绝对 EE。优先 ee（WLA 相对动作可直接组合）。

再加：

- 32 任务 × 每任务 1 条 episode 的 parity smoke test。
- 训练/评测键集合 diff 为空。
- `pivot`/EE 绝对值的范围检查。
- p99 延迟测试。
- 断网/超时/异常动作的降级测试。

**IPT 的验收**：B0（无 IPT）vs B1（有 IPT）在同一本地 LPL 上比较；如果 B1 的提升主要来自“键对齐/动作桥”，说明 IPT 有效；如果 B0 直接崩，说明之前的离线指标不可信。

### C.4 CPSC：Camera Pose Self-Calibration

**问题**：评测不提供 `state_d435`/`state_torso`；头部相机可能有运动；每任务 `camera_params` 不同；`cam_left_high/right_high` 是否与数据集同一对/同矫正未知。

**可用信号**：

- `lower_body[15]` + `waist_state_joint`（训练时）→ waist/legs；URDF FK → torso/head。
- `state_d435`（训练时）→ 头部相机在 base 系的 pose 标签。
- 双目图像 + `camera_params`（训练时）→ 相对深度/三角化。
- 机器人 EE pose + 夹爪接触 → 手眼标定。
- OCB 的 AprilTag → 绝对 6D pose 标签；F/T → 接触标签。

**方案**：

1. **URDF FK**：用 `g1_description`（23/29 DoF，BSD-3）从 `lower_body`/waist 推 `T_base_torso`；头相机 mount 固定时，`T_base_d435 = T_base_torso @ T_torso_d435`。
2. **蒸馏头**：训练一个轻量 head，从 4 路 RGB + proprio 预测 `state_d435`（6D）和 `state_torso`（6D）；用官方数据的标签监督；部署时不需要这些键。
3. **自标定**：用双目/时序 PnP/pose graph  refine 头部外参；OCB 的 AprilTag 提供绝对基准；评测时用前 N 帧做一次校准，之后固定/缓慢更新。
4. **鲁棒性**：训练时随机扰动内外参（fx/fy/cx/cy、R/T）、随机裁剪/resize、随机遮挡；让编码器不依赖精确标定。
5. **Fallback**：如果自标定不稳定，直接用数据集每任务 `camera_params` + 固定 mount 假设；再加腕部相对伺服，减少对头部绝对精度的依赖。

**方程**：

```text
T_base_d435 = T_base_torso @ T_torso_d435
T_cam_obj   = T_cam_base @ T_base_obj
e_reproj    = || π(K, T_cam_obj, X_obj) − x_pixel ||²
T*          = argmin_T Σ e_reproj + λ ||T − T_prior||²
```

**验收**：在留出任务上，`state_d435` 平移误差 <1cm、旋转 <3°；如果达不到，不把 CPSC 当硬依赖，改用相对腕部视觉伺服。

### C.5 动作桥：从 WLA 到挑战 API

| 模式 | WLA 输出 | 挑战 API | 桥 |
|---|---|---|---|
| EE | 相对 `xyz+rotvec/rot6d` | 绝对 `xyz+rpy` | `T_abs = T_curr @ T_rel`；转 rpy；clamp |
| Joint | 绝对关节 | 绝对关节 | 直接映射；检查顺序/符号 |
| Pivot | WLA 无 | `pivot[7]` | 新头/映射；安全限幅 |
| Gripper | 1+1 | 1+1 | 直接；二值化/连续按数据集 |

工程顺序：先冻结 WLA，只加 `(waist, base_command, legs) → pivot` 的小 MLP/头（1–2 天可跑）；如果 pivot 误差/漂移大，再改 54D layout 重训 action head。两条路都要在 held-out 上验证 pivot 语义，不能只看训练 loss。

**伪代码**：

```python
def to_eval_action(pred, obs, control_space):
    if control_space == "ee":
        T_curr_l = pose6_to_se3(obs["left_ee_pose_gripper_base"])
        T_curr_r = pose6_to_se3(obs["right_ee_pose_gripper_base"])
        T_l = T_curr_l @ se3_from_rel(pred["left_rel"])
        T_r = T_curr_r @ se3_from_rel(pred["right_rel"])
        out_l = se3_to_pose6(T_l)  # xyz + rpy
        out_r = se3_to_pose6(T_r)
    else:
        out_l = pred["left_arm"]
        out_r = pred["right_arm"]
    return {
        "meta.token": TOKEN,
        "action.left_gripper": pred["left_gripper"],
        "action.right_gripper": pred["right_gripper"],
        "action.pivot": pred["pivot"],
        f"action.{'left_ee_pose_gripper_base' if control_space=='ee' else 'left_arm'}": out_l,
        f"action.{'right_ee_pose_gripper_base' if control_space=='ee' else 'right_arm'}": out_r,
    }
```

**安全**：

- 工作空间 box + 速度/加速度限幅；异常值拒绝并回退到上一帧。
- 如果 `pivot` 语义不确定，先小步探针；记录响应。
- 不要输出评测不接受的键；多余键会被拒绝。

### D.5 为什么 success-only 不够（形式化）

设成功数据分布为 `p_succ(s,a)`，评测分布为 `p_eval(s,a)`。评测含位置/干扰物/背景/未见物/人为撤销，`p_eval` 在 `p_succ` 支撑集外有质量。BC 最小化：

```text
L_succ(θ) = E_{(s,a)∼p_succ} [ −log π_θ(a|s) ]
```

它不惩罚 `p_eval(s)>0` 但 `p_succ(s)=0` 的状态。增加 `p_succ` 样本不会降低这些状态上的误差；这就是“再多成功演示也修不好撤销”的原因。

三个具体机制：

1. **协变量漂移**：评测初始状态/背景/物体不同，策略进入训练没见过的状态，误差累积。
2. **因果混淆**：success-only 中某些视觉线索与动作虚假相关（例如某背景总配某动作）；反事实数据打破。
3. **接触/力缺失**：最后几毫米的插入/拧盖/拉拉链需要力/接触反馈；success-only 没有负样本/力标签，模型只能学“看起来像”。
4. **进度单调**：没有 undo 标签，进度头倾向单调；撤销后继续执行错误子目标。
5. **长程复合**：32 任务中 25–37s 的任务多，单步误差会复合；belief state 提供可检查的中间状态。

## F. CSCE：Counterfactual State-Coverage Engine

### F.1 流水线

```text
任务选择 → 采集（成功/失败/恢复/接触/未见/背景/撤销）
        → 自动标签（AprilTag/F-T/几何/状态机）
        → 质量门禁（同步/标定/多样性/泄漏）
        → 主动选择（覆盖/不确定度/成本）
        → 混合训练（官方 32k + OCB 3–5k）
        → 本地 LPL（32×10）→ 失败分类 → 下一轮
```

### F.2 采集协议

| 阶段 | 任务 | episodes | 重点 |
|---|---|---|---|
| P0 | T10/T14/T16/T19/T27 | 500 | 接触/撤销 |
| P1 | +T05/T09/T12/T24/T28/T29 | 2000 | 长程/移除/重置 |
| P2 | 全 32 任务 | 3000–5000 | 覆盖缺口 |

- 选择理由：P0 的 T10/T14/T16/T19/T27 覆盖插头、拧盖、叠毛巾、拉拉链、叠碗，都是“接触最后几毫米 + 官方撤销”的高杠杆任务；P1 的 T05/T09/T12/T24/T28/T29 覆盖长程、移除、重置、未见物。
- 每个任务：成功 30%、失败 25%、失败后恢复 20%、接触/对齐 15%、未见/背景 10%。
- 失败要“有意义”：接近成功但滑/偏/未对准/力过大/顺序错；不要随机乱动。
- 恢复要“最小修复”：只重做被破坏的子目标，不从头重跑。
- 采集者：G1 遥操作（xr_teleoperate）优先；SO-101/HandUMI 做代理；同一任务两种 embodiment 都采，训练时域随机化。

### F.3 主动选择

目标：在预算 B 内最大化覆盖/收益。

```text
max_{S⊆U, |S|≤B} Σ_{i∈S} [ α·Coverage(i) + β·Uncertainty(i) − γ·Cost(i) ]
```

- `Coverage(i)`：FBS 状态空间的新覆盖（pose/contact/phase 的 bin/核密度）。
- `Uncertainty(i)`：FBS 的 pose 方差/contact 熵/phase 熵/ensemble 分歧。
- `Cost(i)`：采集时间/操作员/重置成本。
- 子模贪心：每轮选边际收益最大；近似 1−1/e。
- 失败优先：`Coverage` 加权 failure/recovery bin；避免只采成功。
- 课程：先易后难；先接触/撤销，再长程/未见。

### F.4 标签

| 标签 | 方法 | 精度目标 |
|---|---|---|
| object/part 6D pose | AprilTag + 已知 CAD/网格；教师（FoundationPose/PartSAM） | <1cm/5° |
| articulation | 视觉 + 状态机 + 人工 | >90% |
| contact | F/T 阈值 + 视觉 | F1 >0.9 |
| force | F/T 直接读 | MAE <1N |
| relation | 几何规则（距离/法向/包含） | >95% |
| phase | score_steps + 状态机 + 人工 | >90% |
| success/failure | 人工 + 自动完成检测 | >98% |
| undo | 脚本标签 + 状态回退检测 | >95% |

- 人工只做抽检/难例；自动标签先跑，人工修正 5–10%。
- 标签版本化；训练/评测 split 按 episode/task，避免泄漏。

### F.5 与官方数据混合

- 官方 32k：成功轨迹、语言、视觉多样性。
- OCB 3–5k：失败/恢复/接触/撤销。
- 采样权重：官方 70–80%，OCB 20–30%；按任务平衡；接触/撤销任务提高 OCB 权重。
- 训练：先官方预训练，再官方+OCB 混合微调；或从一开始混合 + 课程。
- 防过拟合：OCB 的物体/背景/布局随机化；held-out 任务/物体评估。

### F.6 质量门禁

- 标定：重投影误差 <2px；F/T 零点漂移 <0.1N；时间同步 <10ms。
- 数据：无丢帧/黑帧/重复帧；动作范围合理；成功/失败标签一致。
- 多样性：物体/背景/光照/位置/干扰时序覆盖；避免单一操作员风格。
- 泄漏：OCB 的物体/背景不出现在评测训练集？至少 held-out 评估。
- 许可：源数据 Apache-2.0；自采数据保留原始许可/同意；提交时披露。

## G. FBS：Factored Belief State

### G.1 状态定义

```text
b_t = { objects, articulation, contacts, relations, phase, uncertainty }
```

- **objects**：任务相关物体/部件；每个有 6D pose `T ∈ SE(3)`、尺度、可见性、cov。
- **parts**：杯把、盘沿、插头 prong、瓶盖、拉链头、毛巾角、碗沿、耳机、手机、便签钉、注射器。
- **articulation**：盖子开合 `q∈[0,1]`、拉链 `q`、抽屉/盒子 `q`、铰链角。
- **contacts**：左/右 gripper 与物体/桌面/目标的 contact；接触点 `p`、法向 `n`、力 `f∈R^3`、cov。
- **relations**：`on/in/stacked/inserted/held/aligned/zipped` 等离散谓词。
- **phase**：任务阶段（approach/grasp/transport/align/insert/release/done）或任务 DAG；progress `π∈[0,1]`。
- **uncertainty**：pose cov、contact entropy、phase entropy、force variance。

JSON 示例：

```json
{
  "objects": [
    {"id": "cup", "pose": {"xyz": [0.1, 0.2, 0.3], "quat": [0, 0, 0, 1]},
     "cov": [0.01, 0.01, 0.01, 0.02, 0.02, 0.02], "visibility": 0.9,
     "parts": [{"name": "handle", "pose": {"xyz": [], "quat": []}}]}
  ],
  "articulation": {"lid": 0.3, "zipper": 0.0},
  "contacts": [
    {"side": "right", "object": "cup", "point": [], "normal": [],
     "force": [0.0, 0.0, 2.0], "cov": 0.1}
  ],
  "relations": [{"subj": "cup", "pred": "on", "obj": "rack"}],
  "phase": {"name": "hang", "progress": 0.6, "entropy": 0.1},
  "uncertainty": {"pose": 0.02, "contact": 0.05, "phase": 0.1}
}
```

### G.2 架构

```text
4×RGB + proprio + language
        ↓
共享 VLM/DiT backbone（WLA/π0.5）
        ↓
┌────────────────────────────────────────────┐
│ object/part queries (16–32)                │
│  ├─ 6D pose head (xyz + rot6d)             │
│  ├─ articulation head (q)                  │
│  ├─ contact head (BCE)                     │
│  ├─ force head (mean + var)                │
│  ├─ relation head (CE)                     │
│  └─ phase/progress head (CE/reg)           │
│ uncertainty head (heteroscedastic/evidential)│
└────────────────────────────────────────────┘
        ↓
FBS tokens + action tokens → action expert
        ↓
pivot / arms / EE / grippers
```

- 所有头共享 backbone；新增参数 1–5%。
- 单 checkpoint；推理一次 forward + 确定性滤波。
- 头可以很小（2–4 层 MLP/Transformer）；pose 头用 crop feature + PnP/回归。
- 训练时可用教师（SAM3/PartSAM/FoundationPose）蒸馏；部署只保留学生头。

### G.3 滤波

**EKF（pose/force）**：

```text
x_t^- = A x_{t-1} + B a_{t-1}
P_t^- = A P_{t-1} A^T + Q
K_t   = P_t^- H^T (H P_t^- H^T + R)^{-1}
x_t   = x_t^- + K_t (z_t − h(x_t^-))
P_t   = (I − K_t H) P_t^-
```

**离散 Bayes（contact/phase）**：

```text
b_t(k) ∝ p(z_t | k) Σ_j T(k | j) b_{t-1}(j)
```

**粒子滤波（多模态/遮挡）**：

```text
particles {x_t^(i), w_t^(i)}
w_t^(i) ∝ w_{t-1}^(i) p(z_t | x_t^(i))
resample if ESS < N/2
```

**因子图（关系）**：

- 节点：物体 pose、接触、phase。
- 因子：pose 先验、视觉观测、接触几何、关系谓词、时序平滑。
- 用 iSAM/GTSAM 或轻量自定义求解；频率 10–30Hz。

**更新顺序**：

1. 视觉/pose 观测 → EKF/UKF；
2. contact/force → 离散 Bayes + EKF；
3. relation → 因子图/规则；
4. phase → HMM/状态机；
5. uncertainty → 传播。

### G.4 损失

```text
L = λ_pose L_pose + λ_art L_art + λ_contact L_contact
  + λ_force L_force + λ_rel L_rel + λ_phase L_phase
  + λ_cal L_cal + λ_temp L_temp + λ_cons L_cons
```

- `L_pose`：平移 L1 + 旋转 geodesic/6D；对称物体用对称感知 loss。
- `L_contact`：BCE + focal；类别不平衡加权。
- `L_force`：Gaussian NLL（mean+var）或 L1 + 校准。
- `L_phase`：CE + progress L1；undo 样本加权重。
- `L_rel`：CE；关系不平衡加权。
- `L_cal`：ECE/Brier/temperature。
- `L_temp`：相邻帧 pose/phase 平滑；动作条件一致。
- `L_cons`：多视角/双目/时序一致性；dropout 一致性。

### G.5 训练

- **标签来源**：OCB 的 AprilTag/F-T/状态机；官方数据的教师伪标签（分割/pose/phase）；自监督时序。
- **教师**：SAM3/PartSAM（分割）、FoundationPose（pose）、DepthAnything/ stereo（深度）、OCR/语言（任务）。
- **域随机化**：物体颜色/形状/材质、背景、光照、相机内外参、遮挡、运动模糊。
- **缺失模态**：随机 drop `state_d435`/`state_torso`/waist/相机/历史；训练时用辅助标签，部署时不依赖。
- **课程**：先静态 pose，再 contact/phase，再 undo/recovery；先 5 任务，再 32。
- **数据混合**：官方 70–80% + OCB 20–30%；接触/撤销任务加权。
- **正则**：pose/force 的物理约束；relation 的几何一致性；phase 的 DAG 约束。

### G.6 运行时

- 头推理 <10ms；滤波 <2ms；总 <15ms；p99 <0.8×chunk。
- 主动感知：若 pose/contact 熵高，腕部小步移动/换视角；否则直接执行。
- 安全：force/contact 异常 → 后退/停止；pose 跳变 → 重观测。
- 降级：FBS 头失败 → 回退到纯 VLA + 规则安全；不要阻塞动作。

### G.7 单模型合规

- 所有 learned 头在同一个 checkpoint；没有第二个独立模型。
- 滤波器是确定性算法，不是 learned model。
- HIM 是同一 checkpoint 的辅助头；规则式安全 monitor 只做急停/限速，不做任务决策。
- OCB 的教师只在离线训练用，不进入提交包。

## H. 策略集成：SARP/HIM/CD/SPA

### H.1 SARP：State-Aware Recovery Policy

**检测**：

```text
undo if phase_t < phase_{t-1} − δ
     or relation_t != relation_{t-1} (lost)
     or object missing/pose jump > threshold
```

**修复**：

1. 找到被回退的子目标 `g`（DAG 中最后一个满足 pre 但未满足 post 的节点）。
2. 只重做 `g` 及其必要前置；不从头重跑。
3. 如果人手仍在附近，等待/后退；人离开后再修复。
4. 如果目标不可达/被移除，重新 grounding 或安全停止。

**例子**：

| 任务 | 回退 | 修复 |
|---|---|---|
| T16 毛巾 | folded→unfolded | 重新对齐→折左→折右→放旁边 |
| T14 药瓶 | cap open→closed | 重新抓盖→拧开→倒药 |
| T19 拉链 | zipped→open | 重新抓拉链头→拉上 |
| T27 叠碗 | stacked→removed | 重新抓第二个碗→叠上 |
| T10 插头 | inserted→pulled | 重新对准→插入 |
| T24 传送带 | placed→start | 重新抓取→分拣 |

**实现**：

- 规则式 DAG + FBS 谓词（首版，安全/可解释）。
- 学习式 recovery head（后续）：输入 FBS tokens + phase，输出子目标/动作。
- 恢复动作限速/限幅；失败两次则安全停止。

### H.2 HIM：Human Interference Monitor

- 输入：RGB + FBS；输出：人手/手臂接近、遮挡、抓取物体、撤销意图。
- 训练：OCB 人手干扰片段 + 公开手部数据（如允许）；同一 checkpoint 辅助头。
- 行为：
  - 人手进入工作区 → 降速/等待；
  - 人手接触目标 → 后退/释放；
  - 人手离开 → 重观测 → SARP。
- 安全兜底：规则式距离/电流/力阈值 → 急停；不依赖学习。
- 合规：HIM 不做任务决策；只做安全/等待；避免“第二模型”争议。

### H.3 CD：Contact Distillation

- 目标：部署不带 F/T，也能估 contact/force。
- 训练：OCB 的 F/T 标签 + RGB/proprio；输出 contact 概率、力 3D/6D、接触点/法向。
- 损失：BCE + Gaussian NLL + 校准 + 物理一致性（力→形变/摩擦）。
- 部署：FBS 的 contact/force 头；无 F/T 输入。
- 验证：held-out 物体/背景的 contact F1、force MAE；如果迁移差，只用作辅助信号，不做硬约束。

### H.4 SPA-VLA：部件 token 表示层

- 教师：SAM3/PartSAM 离线生成部件 mask/centroid/affordance；不进入提交包。
- 学生：VLA 内部 16–32 个 part queries + mask/centroid 头；与动作头同一 checkpoint。
- 用途：FBS 的 part pose/contact 输入；语言 grounding；未见物体泛化。
- 不再单独作为主卖点；如果 A4（oracle mask）提升 <2pp，停止扩大 part head。

### H.5 动作桥（策略侧）

- 优先 `control_space="ee"`：WLA 相对动作 → 绝对 EE → 挑战 API。
- `pivot`：单独头；训练用 `action.pivot`；部署 clamp/限速。
- joint 模式：绝对关节；检查顺序/符号；适合非 WLA 底座。
- chunk：8–30；receding horizon；动作平滑（低通/限速）。
- 异常：NaN/超范围/跳变 → 回退上一帧/零动作 + 安全停止。

### H.6 控制循环

```python
while not done:
    obs = get_obs()
    b = fbs.update(obs)                 # pose/contact/phase/uncertainty
    if him.hand_near(obs, b):
        action = safe_wait_or_retreat()
    else:
        g = sarp.select_subgoal(b)      # DAG + undo detection
        a = policy.act(obs, b, g)       # single checkpoint
        action = bridge.to_eval(a, obs)
    send(action)
```

**时序**：

- `get_obs` 网络传输；`fbs.update` <2ms；`policy.act` 10–50ms（取决于模型）；`bridge` <1ms。
- 若 p99 超预算：减 chunk/模型量化/缓存视觉特征/共享后端。

## K. 风险、fallback、合规

### K.1 规则风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 外部数据/模型禁止 | OCB/CSCE 不能训练 | fallback B：官方数据自监督 + 反事实增广；OCB 只评测 |
| 单模型定义严格 | HIM/FBS 辅助头争议 | 所有 learned 头同一 checkpoint；规则式 monitor 不做任务决策 |
| 评测硬件不可改 | OCB 不能接评测 | OCB 仅离线；无额外传感器 |
| 任务硬编码禁止 | DAG/脚本风险 | 用 FBS 谓词 + 学习策略；DAG 只做高层选项，不做固定轨迹 |
| 在线 API 禁止 | 不能调 LLM/VLM | 离线编译/本地模型 |
| 数据许可 | 不能提交派生数据 | Apache-2.0 源；自采数据披露/同意；只提交模型 |

### K.2 技术风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| Pose 精度不足 | FBS 无用 | 腕部近景/相对伺服；只用 contact/phase |
| Contact 迁移差 | CD 无效 | 域随机化/held-out；辅助信号 |
| 数据质量 | 训练噪声 | 自动门禁 + 双人复核 |
| 延迟 | 评测超时 | 小头/量化/共享后端/减 chunk |
| Sim2real | OCB 不迁移 | 真实 OCB + 域随机化；G1 适配件 |
| 过拟合 OCB | 评测差 | held-out 任务/物体；官方数据主权重 |
| 撤销检测误报 | 反复修复 | 滞回/连续帧确认；失败两次停止 |

### K.3 安全风险

| 风险 | 缓解 |
|---|---|
| 干扰臂撞 G1/人 | 力限幅/隔离区/急停/速度限制 |
| 人手干扰 | 安全距离/培训/同意/HIM 等待 |
| G1 失稳 | 默认静态 base/waist；小步探针；限幅 |
| 夹爪夹人 | 力限/急停/工作区隔离 |
| 数据隐私 | 不采集人脸/声音；同意/脱敏 |

### K.4 Fallback 阶梯

| 级别 | 方案 | 触发 |
|---|---|---|
| A | 完整 SCF | 规则允许 + 数据/模型收益达标 |
| B | 官方数据 + 官方允许的底座/小模型 + 自监督 FBS + 反事实增广；OCB 只评测 | 外部数据/模型禁止 |
| C | IPT/CPSC + Portfolio + SPA-VLA；不采新数据 | 数据/时间不足 |
| D | WLA/π0.5 + IPT + Compliance；安全提交 | 全部不达标 |

### K.5 合规 checklist

- [ ] 单 checkpoint；无多模型混合。
- [ ] 不用 task id；无任务硬编码轨迹/坐标。
- [ ] 不改评测机器人硬件；OCB 离线。
- [ ] 外部数据/模型披露；许可证/NOTICE。
- [ ] 动作只输出评测接受的键；形状/dtype 正确。
- [ ] N 端口/令牌/状态隔离/并发。
- [ ] p99 延迟/异常动作/断线降级。
- [ ] 人机安全/急停/工作区。
- [ ] 数据同意/隐私/脱敏。
- [ ] 评测日志/可复现。

### K.6 开源回馈与伦理

- OCB 的 BOM/布局/标定/采集脚本在赛后以 MIT/Apache-2.0 开源；不包含个人视频/人脸。
- 自采数据只发布标签/统计/基准；原始视频经同意/脱敏，不发布可识别个人的内容。
- HIM 只做接近/遮挡检测，不做身份识别、人脸识别、情绪识别。
- 不把人类演示用于伤害性/监控性任务；遵循“人类共同利益”的用途边界。
- 评测/论文披露外部数据/模型/硬件与许可证；结果可复现。

## M. 开放问题

1. **外部数据/模型**是否允许？若允许，WLA/π0.5 + OCB 可用；若不允许，切 fallback B（官方数据自监督 + 反事实增广，OCB 只评测）。
2. **N 台机器人/端口**具体值？README 示例 N=3；按 N 可配置共享后端/独立进程。
3. **控制频率/chunk 映射**？`action_chunk_size` 与真实控制周期如何对应？需实测 p99。
4. **4.2 评分聚合**：每任务步骤分是 trial 平均还是其他？Q 是否按任务归一化？
5. **4.3 排名/入围**：榜单入围条件、成绩记录、提交日期？
6. **单模型定义**：辅助头/测试时滤波/规则式安全 monitor 是否算“多个模型”？
7. **task id**：评测是否传 task id？我们主动不用；若只给 task id 不给语言，需要适配。
8. **语言**：评测用 5 条复述、未见复述、还是中文？先做留一法/约束图。
9. **人为干扰协议**：脚本化还是自适应？时序/频率未知；先按备注构造测试。
10. **base/waist 限制**：是否允许移动底座/腰部？默认静态 + 探针。
11. **真实榜单**：公开榜仍是占位；真实排名/强基线不可见；不要用假分数做决策。
12. **派生标签许可证**：部件 mask/pose/contact 标签由我们生成；源数据 Apache-2.0；提交时保留 NOTICE/披露。
13. **pivot 语义**：`pivot[7]` 每一维的物理含义/单位/限位？先用数据统计 + 小步探针。
14. **评测相机**：`cam_left_high/right_high` 是否与数据集头部双目同一对？是否矫正？内外参？CPSC 先兜底。
