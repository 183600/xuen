# 第 2 轮（UniBot 线 · 承接第 1 轮；本轮灵感：「需求洞察」×「惯性测量单元」）

> **轮次说明**：本次任务提示写的是“第 1 轮”，但状态文件里已经有第 1 轮 UniBot-SAGE 奠基版。为保持跨轮连续性，本轮记为**第 2 轮**；不重新基线化，定义续 U13–U25、引理续 L8–L12、实验续 E619–E632。
> **情报核实（2026-11-19，本轮重新拉取）**：已重新核对官方提交 README（英文 / 中文）与 HuggingFace 数据集卡片、datasets-server 首行 schema。第 1 轮的关键结论仍成立，但发现**三处必须在第 2 轮修正的接口事实**（见 §0）。本轮所有新设计都以这三处修正为前提。

## 0. 本轮先做的“事实校准”（不是文献综述，是接口审计）

### 0.1 评测接口到底给了什么、没给什么

| 通道 | 评测接口 | 数据集里有但评测不暴露 | 对研究的含义 |
|---|---|---|---|
| 图像 | 头左/头右/左腕/右腕，4×480×640 RGB | — | 视觉是主传感器，但头相机是立体整流图，可做视觉自运动估计 |
| 臂 | `left_arm`/`right_arm` 各 7 维**关节位置** | 关节速度、力矩、电流 | 速度/加速度只能差分，噪声大 |
| 末端 | `left/right_ee_pose_gripper_base` 各 6 维（xyz+rpy） | 躯干系 EE 位姿、D435 位姿 | 可用二阶差分做“伪惯性”信号 |
| 夹爪 | `left/right_gripper` 各 1 维（Dex1，5.5 开 → 0 闭） | `gripper_controls` 4 维（trigger/squeeze） | 只有开度，没有力/触觉；但开度轨迹本身含“抓握冲激响应” |
| 下身 | `lower_body` 15 维 | `left_leg`/`right_leg` 各 6 维、`waist_state_joint` 3 维、`state_torso` 6 维 | **评测只给腿+腰的关节位置**；没有 IMU 的角速度/线加速度，也没有躯干位姿 |
| 语言 | `observation.language` 单个 str | — | 任务需求被压成一句话，终态判据不可直接读出 |
| 时间 | 无 timestamp / frame_index | 数据集有 `timestamp`/`frame_index` | 评测端不告诉你 dt；差分只能按“控制步”做，不能声称物理秒 |
| IMU | **没有** | 数据集也没有显式 IMU 字段 | “惯性测量单元”必须以**功能替代**而非“读取 IMU”来兑现 |

**一句话**：任务最需要的接触/插入/滑移信息，恰好是接口最不给的；而接口给的最像“惯性”的东西，只有 EE 位姿的二阶差分、夹爪开度的冲激响应、以及 `lower_body` 里腰关节的姿态代理。

### 0.2 三处必须修正的工程事实（第 1 轮方案里的隐患）

1. **`action_chunk_size` 是 metadata 里的静态声明**（README §1/§3：它是“每次返回动作的前置时序维度长度”）。第 1 轮 U8 假设可以在运行时按相位改变 chunk 长度，这在最严格解释下会被评测端按固定形状校验 ⇒ **默认合规形态改为全局固定 T_a**（建议 4；延迟吃紧时 8），不在运行时改变数组长度。若要做“自适应”，必须先向组委会书面确认允许变长，或退化为“按任务簇在提交前选不同固定 T_a 的版本”。
2. **`reset()` 与 `get_action(obs)` 都没有 port 参数**（README §1）。第 1 轮伪代码里的 `reset(port)` / `get_action(obs, port)` 不是官方接口。正确做法：每个端口一个 policy 实例（官方 Approach 1），或在 server wrapper 里按连接维护 session，再适配成零参 `reset()` / 单参 `get_action(obs)`。
3. **评测观测目录没有 `left_leg` / `right_leg` / `waist_state_joint` / `state_torso` / `state_d435`**。这些字段只在数据集里；πIMU 在评测时只能用 `lower_body` 的腿+腰关节位置，不能直接读躯干姿态或相机位姿。任何“读 `state_torso` 做惯性估计”的方案都必须标成**离线 oracle 分析**，不能写进在线策略。

> 这三条看似工程细节，实际上决定了本轮两个灵感的可行性边界：**“需求洞察”必须在缺失终态标签下做；“惯性测量”必须在缺失 IMU 下做。** 这正是本轮的研究张力。

## 1. 直觉：两个灵感其实在说同一件事的两半

### 1.1 「需求洞察」：这里的“用户”不是人，是隐藏的成功判据

直觉上，“需求洞察”像是产品经理去问用户想要什么。但在这个赛题里，真正的“用户”有两个：

- **评测器的成功判据**：一句话指令只是需求的**有损压缩**。`"plug in the ethernet"` 至少隐含：插头要对准、要插到位、可能要听到/感到“咔哒”、不能只搭在口上；`"hang the cup"` 隐含：杯柄要真的挂住钩子，而不是放在旁边；`"zip up"` 隐含：拉链要闭合，而不是只抓了一下拉链头。
- **可信度审计器**：官方明确会看 per-step 延迟及其波动、动作统计规律性。它要的是“稳定、良构、不异常”的交互，而不是“分数高但动作像脚本”。

所以本轮把“需求洞察”拆成两层：

- **任务需求**：这个任务到底要求什么终态？容差多大？需要接触/插入/旋转/支撑吗？该坚持多久、什么时候该停？
- **审计需求**：我们的验证行为不能制造延迟尖峰、动作离群或明显不自然的周期模式。

第 1 轮的 IP-01 已经意识到“通用 = 技能向量”，但那只回答了“这个任务像哪个任务”。本轮要再往前一步：**不问“是哪个任务”，而问“这个任务要求什么”**。前者容易退化成 32 路硬编码；后者是一个连续的需求向量，能插值到未见任务，也更符合“通才模型”的合规精神。

### 1.2 「惯性测量单元」：不是要读 IMU，而是要重建 IMU 的“功能”

IMU 在机器人里最值钱的不是绝对精度，而是三件事：

1. **事件定时**：接触开始/结束、滑移、卡住、释放——这些是高频变化，视觉 30 Hz 往往慢半拍；
2. **动态响应辨识**：同样的命令，夹爪夹到物体和夹到空气的响应不同；物体的质量/摩擦/形状会改变“命令→运动”的传递函数；
3. **外部扰动检测**：人推了机器人、桌面被碰、底座漂移——这些在“人为干扰”泛化场景里直接决定成败。

评测接口没有 IMU，但有三个可用的“功能替代”：

- **EE 位姿的二阶差分** ≈ 末端的线加速度/角加速度（需要平滑，噪声大）；
- **夹爪开度对闭合命令的响应** ≈ 夹爪-物体系统的冲激响应（这是本轮最惊喜的信号：夹到物体时开度会停在某个平台，夹空时会一路到 0）；
- **头立体视觉的自我运动残差 + `lower_body` 腰关节** ≈ 底座/躯干的姿态代理（只能做“是否被扰动”的检测，不能做高精度惯性导航）。

因此本轮不叫“用 IMU”，而叫 **πIMU（pseudo-IMU，功能惯性观测器）**：不追求米/秒²的绝对准确，只追求**事件定时**和**动态响应分类**。这是把“缺失传感器”转成“可检验的估计问题”，而不是假装传感器存在。

### 1.3 合成：需求告诉你“验什么”，惯性告诉你“什么时候验”

把两个灵感接起来，得到一个很自然的闭环：

> **RIVL（Requirement–Inertial Verification Loop，需求-惯性验证环）**
> 先从语言 + 成功示范推断需求向量 r → 用 πIMU 在对的时机检测接触/滑移/卡住/释放事件 → 更新“这个需求是否已满足”的信念 b_t → 决定继续 / 验证 / 重试 / 停止。

核心假设不是“我们的控制更强”，而是：**最后一公里的失败里，有一部分不是“做不到”，而是“不知道有没有做到、不知道什么时候该停/该改”。** 这类失败可以用很小的验证预算救回来，而且不需要新硬件、不需要评测侧信息、不需要多模型。

## 2. 量化证据：为什么是“验证缺口”，而不是又一轮“更大模型”

### 2.1 旧证据复核（teaser 榜，n=256 个 model-task 点，2026-11-17）

本轮重新计算，数字与第 1 轮一致：

- `step_score ≈ 1.3374·success + 0.0929`，`R² = 0.99548`，`r = 0.99774` ⇒ 两项指标近乎共线，终态成功是唯一独立杠杆。
- 8 个模型两两跨任务 Kendall τ：均值 **0.0639**，中位 **0.0718**，范围 **[−0.107, 0.202]** ⇒ 强弱在任务间近乎准正交。
- 每任务 oracle = **33.96**，最好单模型 = **29.70**，差 **+4.26**；每任务 top-2 = **32.22**，差 **+2.52**。
- 每任务跨模型成功率极差均值 = **17.93** 分 ⇒ 任务间的“可争夺空间”很大。

### 2.2 新证据 A：高方差任务恰好是“终态判据不显然”的任务

按跨模型成功率变异系数 `CV = sd/mean` 排序（teaser，n=8 模型/任务）：

| 任务 | 均值 | sd | CV | 区间 | 为什么像“需求歧义” |
|---|---:|---:|---:|---|---|
| Hang the Cup | 23.0 | 9.5 | **0.414** | 9.0–38.4 | “挂住”是离散终态，阈值/钩入深度不显然 |
| Organize Stationery | 22.5 | 7.7 | **0.343** | 9.1–33.1 | “整理好”的布局判据不唯一 |
| Unlock | 20.1 | 6.4 | **0.318** | 6.3–28.2 | 需要旋转到某个角度/力矩，成功瞬间不可见 |
| Stack Bowls | 24.1 | 7.6 | **0.314** | 11.3–36.3 | 叠放稳定性 vs 仅接触 |
| Plug In Ethernet | 17.7 | 5.4 | **0.306** | 9.2–27.5 | 插入深度/卡扣是否到位 |
| Remove Pinned Note | 27.3 | 8.1 | **0.299** | 13.3–40.3 | 拔出 vs 撕破的判据 |
| Zip Up | 23.4 | 7.0 | **0.298** | 13.6–33.4 | 拉链是否真正闭合 |
| Plug Charger | 25.6 | 7.5 | **0.295** | 16.5–38.2 | 插入/接触判据 |
| Spell robot | 21.8 | 6.1 | **0.281** | 14.4–34.0 | 字符布局的终态匹配 |

注意：CV 高也可能是“能力差异”而不是“判据歧义”，两者在 teaser 表上不可完全分离。因此这是一个**待检验假设**，不是结论。本轮把它写成可证伪实验（E625/E630）：若“按需求定制的停止/验证策略”在高 CV 任务上没有超过固定超时基线，则“需求歧义”解释不成立，RIVL 降级为分析工具。

### 2.3 新证据 B：任务内“做得久”既可能更好，也可能更差

对每个任务，在 8 个模型上算 `corr(success, duration)`：

- 全部 32 任务的均值 `r = −0.011`（与第 1 轮一致：总体上“快”没有红利）；
- 但平均 `|r| = 0.293`，且符号高度异质：
  - **越久越好**：Fruit Basket Collection `+0.66`、Toolbox Storage `+0.59`、Organize Bookshelf `+0.52`、Unlock `+0.48`；
  - **越久越差**：Spell robot `−0.83`、Arrange Test Tubes `−0.72`、Color Arrangement `−0.58`、Stack Cups `−0.45`、Plug In Ethernet `−0.41`。

这不是“全局该快还是该慢”，而是**每个任务有自己的“坚持预算”**：有些任务需要多次尝试/微调，有些任务一旦方向错了，越坚持越糟。第 1 轮把 `τ_persist` 当成全局超时，是过度简化；本轮把它变成需求向量的一维。样本只有 8 个模型/任务，且是 teaser，故只作为先验，不作为定律。

### 2.4 新证据 C（官方数据 pilot）：夹爪开度平台是一个便宜且可解释的“抓握占用”信号

在 `G1_Dex1_PlugInEthernet` 上做了一个**小样本、无真值标签**的 pilot（2026-11-19，30 个 100 帧窗口，30 Hz）：

- 扫描到 7 次明显的夹爪闭合事件（10 帧内开度下降 > 2.0）；
- 闭合后窗口末端开度中位数呈两类：**空夹 ≈ 0.13–0.14**；**疑似夹到物体 ≈ 0.57, 0.61, 1.11, 1.18, 2.81**（Dex1 5.5 开 → 0 闭）。
- 在 episode 0 的前 100 帧（0–3.3 s，接近阶段，夹爪静止）里，直接对 EE 位置做二阶差分，加速度峰值可达 ~10.6 m/s²（噪声主导）；在另一段 400 帧（帧 300–699，约 13.3 s，含夹爪闭合）里，用 Savitzky–Golay（窗 9、二阶）平滑后峰值 ~1.24 m/s²、均值 ~0.1–0.2 m/s²。该段夹爪闭合时 EE 几乎不动，说明**“接触”不一定在 EE 加速度上显形，反而在夹爪开度平台上更清楚**。

pilot 的结论不是“我们已经会抓握检测了”，而是：

1. 夹爪开度平台比 EE 加速度更稳健地指示“夹到东西/夹空”；
2. 原始二阶差分噪声很大，πIMU 必须做平滑/变点检测，不能裸阈值；
3. 没有真值标签时，平台值只能说“疑似”，必须用腕部视觉 + 抬升测试交叉验证。

### 2.5 观测性缺口（本轮的研究对象）

把“任务需要什么”与“接口给什么”对齐，得到一张缺口表：

| 任务需求 | 接口是否直接给 | 可用的替代信号 | 替代的失效模式 |
|---|---|---|---|
| 接触开始/结束 | 否（无触觉/力/IMU） | EE 加速度、腕部光流高频能量、夹爪开度平台 | 腕部遮挡、EE 位姿量化、30 Hz 混叠 |
| 滑移 | 否 | 腕部图像中物体相对夹爪的运动、开度高频抖动 | 纹理弱/透明物体、快速运动模糊 |
| 插入到位 | 否 | EE 速度-命令残差、微退测试、腕部视觉 | 卡住与“已到位”在残差上可能同形 |
| 释放稳定 | 否 | 张开后物体是否随动、头相机视觉 | 遮挡、物体滚动 |
| 底座/躯干扰动 | 否（无 IMU；`state_torso` 不暴露） | 头立体视觉自运动残差、`lower_body` 腰关节 | 视觉退化、腰关节被命令运动混淆 |
| 终态成功 | 否（无 success flag） | 成功示范的终态分布 + 学习到的判据分类器 | 示范只有成功样本、无负样本 |

**本轮的核心研究问题因此不是“如何更强”，而是“如何在缺失模态下，把验证做成一个可校准、可回退、可审计的决策问题”。**

## 3. 研究问题（本轮版）

- **Q1（需求可推断性）**：能否从语言 + 成功示范的统计量，推断一个连续需求向量 `r = (ε_p, ε_o, c, τ_p, φ, s, β)`（位置/姿态容差、接触 regime、坚持预算、终态判据、安全探针幅度、支撑要求），并在未见任务上插值？它比“任务 id token”更可泛化吗？
- **Q2（πIMU 事件可检测性）**：在没有 IMU、没有时间戳、只有 EE 位姿/夹爪/关节位置/图像的条件下，能否重建“接触开始、滑移、卡住、释放、底座扰动”的事件定时？其 AUROC/定时误差/误报率是多少？哪些通道贡献最大？
- **Q3（验证的净收益）**：在“高需求歧义”任务子集上，需求条件化的“验证/停止/重试”策略能否超过固定超时 + 开环执行？代价是多少时间/延迟？会不会把可救的失败变成硬失败？
- **Q4（主动探针的边界）**：小幅、可逆的探针（微推、微转、抬升测试、微退测试）能否在不扰动场景的前提下降低需求不确定性？探针的安全包络如何定义？什么时候“不探”更好？
- **Q5（合规形态）**：需求条件化是否仍是“一个 checkpoint、一个 API”？固定 `action_chunk_size`、零参 `reset()`、无 port 参数的前提下，如何实现按端口隔离与事件触发的高频反馈？
- **Q6（可信度）**：验证行为会不会制造延迟尖峰、动作离群或明显规律性，从而伤害官方“交互可信度”评估？如何把验证调度做成有预算、可审计、平滑的？
- **Q7（信息价值）**：如果官方未来愿意多暴露一个信号（真 IMU/力/触觉/`state_torso`），哪个信号对最后一公里的边际价值最大？能否用离线 oracle 给出上界，作为对赛道的公共品？

## 4. 设计原则（在 P1–P6 上追加）

- **P7 需求先行**：任何“更用力/更快/更久”的改动，必须绑定到需求向量的某一维；没有需求目标的参数堆叠一律不做。
- **P8 事件定时优先于度量精度**：πIMU 只对“变化”负责，不对“绝对加速度”负责；用尺度不变/序数特征，避免未知 dt 带来的伪精确。
- **P9 先验证再宣告**：终态成功是唯一计分货币，而“宣告成功”的假阳性代价高于“多花几秒验证”的假阴性代价；高歧义时默认验证。
- **P10 观测性诚实**：明确写出“这个信号估不出来”；估不出来就不触发，不用噪声硬凑。
- **P11 探针最小且可逆**：主动探针只在安全包络内、只在低风险相位、只做一次；探针失败必须能回到探针前状态。
- **P12 不伪装传感器**：永远叫 πIMU，不声称读了 IMU；离线 oracle 只用于验证，不进入在线策略。

## 5. 本轮方案：UniBot-SAGE / IRIS

给这条线起一个可记忆的名字：**IRIS = Inertial–Requirement Inference & Servoing**（惯性-需求推断与伺服）。它不是推翻 SAGE，而是把 SAGE 的“接地层”和“适应层”补上缺失的两块：

```
                 ┌────────────────────────────────────────────┐
                 │  需求层  NeedSpec (IP-09)                   │
                 │  r = (ε_p, ε_o, c, τ_p, φ, s, β)            │
                 │  从语言 + 成功示范统计推断；熵 H(r) = 歧义度 │

                 ┌───────────────▼────────────────────────────┐
```

**与第 1 轮的关系**：

- **保留**：IP-06（代理评测）、IP-02（抓握验证）、IP-03（chunk 缝合/延迟）仍是必保；IP-01（技能路由）继续等合规确认；IP-04（上下文调制）降为 P1；IP-05（pivot 先验）降为 P2（pivot 语义仍未证实）；IP-07 暂存。
- **深化**：IP-02 从“三信号抓握分类器”升级为“夹爪平台 + GIS + 腕部视觉”的可解释验证；IP-03 从“运行时自适应 chunk”修正为“固定 T_a + 事件触发的验证调度”。
- **新增**：IP-09（需求推断）、IP-10（πIMU）、IP-11（RIVL）。这三项构成本轮的主线。

**为什么不是“更大模型”**：teaser 榜的跨任务 τ 近零，说明“通用”不是一根标量；但本轮不直接赌“多专家路由”（合规风险高），而是赌**同一个模型 + 需求条件化的验证行为**。这条路的边际成本低、可回退、与单一 checkpoint 兼容。

## 6. 最小可提交闭环（MVP v2）与退化链

**MVP v2 = 基线策略 + IP-02（夹爪平台 + 腕部视觉）+ IP-10（被动 πIMU 事件）+ IP-11（只做“继续/停止/重试”，不做主动探针）+ IP-03（固定 T_a=4 或 8）+ IP-06（代理评测）**。

关键取舍：**Phase 1 不做主动探针**。先用“被动观察 + 事件触发验证”证明净收益；如果 E623 都不过，主动探针没有意义。这样也把“探针扰动场景”的风险推迟到有证据之后。

**退化链（任何一环失败都不改变基线行为）**：

- Level-0 需求推断不可用/熵过高 ⇒ 用全局默认 `r0`（中等容差、无验证、固定超时）；
- Level-1 πIMU 事件置信度低 ⇒ 不触发验证，退回开环；
- Level-2 验证测试不安全/超时 ⇒ 跳过验证，继续原策略；
- Level-3 需求条件化模块整体失败 ⇒ 退回第 1 轮 IP-02/IP-03 + 基线；
- Level-4 新链路导致延迟超预算 ⇒ 关闭 πIMU/验证，只保留基线提交。

**安全网**：始终保留一份“能跑通、可信度合规、无新模块”的最小提交；新模块通过环境变量开关，默认可关。

## 7. 预期贡献（本轮新增）

1. **需求向量的可操作定义**：把“任务要求”从一句自然语言，变成可估计、可校准、可插值的 `r`；给出容差/坚持预算/终态判据的离线估计方法。
2. **πIMU 的功能定义与基线**：在缺 IMU、缺时间戳的接口下，给出事件定时的可用信号集、平滑/变点方法、以及与离线 oracle 的对照协议。
3. **“验证缺口”的量化**：用 teaser 的高 CV 任务 + 官方数据 pilot，提出并检验“最后一公里有一部分是验证问题”的假设；无论成立与否，都能给赛道一个可复用的失败分解口径。
4. **合规修正**：把第 1 轮的运行时 chunk、port 参数、`state_torso` 依赖三处隐患改正，给出固定 T_a / 零参 reset / 端口隔离的可提交形态。
5. **信息价值报告（公共品）**：用离线 oracle 估计“如果多给一个 IMU/力/`state_torso`，事件检测能提升多少”，为组委会的接口设计提供依据。

## 8. 本轮最大风险

**一句话**：πIMU 是“用现有通道猜缺失模态”，而它最需要可靠的时刻（腕部遮挡、EE 位姿量化、未知 dt、30 Hz 混叠的接触/插入瞬间）恰好是它最不可靠的时刻；一旦事件误报，验证就会从“救回失败”变成“打断本来能成功的执行”，因此本轮必须把“不触发”作为默认安全态，并用离线 oracle 与高精度门控证明“触发”确实比“不触发”好。

## 9. 下一轮迭代计划（深化与修剪）

### 1.1 评测观测目录 vs 数据集字段

**推论**：

1. 在线可用的“惯性”信息只有：EE 位姿二阶差分、夹爪开度冲激响应、腕部图像高频运动、头立体视觉自运动、`lower_body` 的腰关节姿态代理。
2. `lower_body` 15 维 = 双腿（hip×3, knee, ankle×2）×2 + 腰（yaw, roll, pitch）；它是**关节位置**，不是 IMU。要把“腰关节角”当姿态代理，必须扣除命令运动的影响。
3. 数据集里的 `state_torso`/`waist_state_joint` 只能做**离线 oracle**，不能写进在线策略；否则会违反“不读取评测侧信息/不依赖未声明通道”的红线。

### 1.2 时序语义

- `obs_delta_indices` 是**唯一**的时序通道：key 决定送哪些观测，value 是相对当前步的帧偏移（≤0、严格递增），长度=叠帧数；历史不足时用第一帧补齐。
- 偏移单位是**控制步**，不是秒；评测接口不提供 `timestamp`。因此差分只能定义为“每控制步”，不能声称物理加速度；未知 dt 必须用尺度不变/序数特征来规避。
- 首帧补齐会在 episode 开头制造“零速度/零加速度”伪信号 ⇒ πIMU 必须有 warm-up gate（前 W 步不触发）。
- `observation.language` 无时间轴，偏移必须恰为 `[0]`。

## 3. 新增/修正创新点详述

### 3.1 IP-09 · NeedSpec：把“需求”变成可估计的向量

**动机（直觉）**：一句 `"plug in the ethernet"` 并没有告诉你“插多深算成功、要不要听到咔哒、允许多大角度偏差”。这些信息藏在**成功示范的终态分布**里：如果所有成功示范的插头最终都进到某个深度、某个姿态范围，那么这个分布就是“需求”的经验定义。把它显式估出来，策略才知道“什么时候该停、什么时候该继续用力、什么时候该换抓法”。

**与现有方案的差异**：

- 现有做法把任务 id 当条件（task token / one-hot）；这在 32 个已知任务上可行，但对“未见物品/未见指令”的泛化场景不友好，也容易滑向硬编码。
- NeedSpec 不预测任务 id，而预测**需求向量** `r`；任务 id 只是 `r` 的一个粗粒度代理。即使两个任务 id 不同，只要需求相同（比如都是“插到卡扣”），策略可以共享行为；反过来，同一任务 id 在不同物体上可能有不同容差，`r` 可以随观测调整。

**形式化**：见 U13–U15。`r = (ε_p, ε_o, c, τ_p, φ, s, β)`。

**离线估计（从成功示范）**：

1. **容差 `ε_p, ε_o`**：对每个任务的所有成功示范，取终态（释放后稳定窗口）的 EE 位姿（有物体位姿更好，但评测接口没有；离线可用腕部/头相机估计）。`ε_p = quantile_{0.9}(‖p_i − median(p)‖)`，`ε_o = quantile_{0.9}(angular_dist(R_i, R_median))`。这不是“物理容差”的精确值，而是**示范一致性**的可操作代理。
2. **接触 regime `c`**：用规则 + VLM 给示范分段打标：
   - `insert`：EE 速度下降但命令继续、夹爪闭合、腕部图像出现“进入孔洞”的遮挡模式；
   - `rotate`：腕部姿态变化 > 阈值且 EE 位置近似不变；
   - `deform`：物体轮廓在腕部图像中连续变化（毛巾、袋子）；
   - `support`：释放后物体仍稳定（叠放/放置）；
   - `contact`：其余接触丰富但非插入/旋转；
   - `free`：自由空间运动。
3. **坚持预算 `τ_p`**：`τ_p = quantile_{0.9}(demo 时长) − median(demo 时长)`，下限设为 1 s；在评测端用控制步表示。它表达“超过这个额外时间，继续坚持的期望收益很低”，而不是硬超时。
4. **终态判据 `φ`**：从一组参数化谓词中选一个（`object_in_container`、`plug_seated`、`cap_removed`、`closure_closed`、`hook_engaged`、`arrangement_matches`、`object_stable_after_release`），用一个语言条件的二分类器在示范终态帧/非终态帧上训练。谓词本身不可直接观测，但可以用视觉 + πIMU 事件近似。
5. **安全探针幅度 `s`**：从示范中接触阶段的位移/旋转幅度取低分位（默认平移 ≤2 mm、旋转 ≤5°），作为 U23 的包络。
6. **支撑要求 `β`**：释放后物体是否保持稳定；从示范终态的视觉稳定性估计。

**在线推断**：

- `q_ψ(r | ℓ, R_t)`：`R_t` 是按语言相似度检索到的 top-k 任务示范统计量；对未见任务，用相似任务的 `r` 加权插值。语言编码用冻结 VLM；不要用任务 id 查表。
- 前 K 帧（建议 0.5–1 s）在线更新：用观测到的物体尺度、桌面高度、夹爪开合范围修正 `ε_p/ε_o` 与 `s`；用 πIMU 事件修正 `c`。
- 输出：`r̂`（后验均值）与 `H(r)`（歧义度）。`H` 高 ⇒ 提高验证预算；`H` 低 ⇒ 允许开环快跑。

**训练/验证**：

- 数据：官方 32 个 LeRobot v3.0 数据集；只使用成功示范（这是本任务的数据现实）。
- 自监督目标：①终态帧 vs 非终态帧的对比学习；②同一任务不同示范的终态一致性回归；③语言改写（paraphrase）后的 `r` 不变性；④留出任务（leave-one-task-out）检验插值。
- 负面样本：成功示范里没有失败，必须从“非终态帧”和“扰动后的状态”构造负样本；这是 IP-09 最大的数据风险。

**可验收**：E620。若 regime 准确率 <0.7 或终态判据 F1 <0.6，则 IP-09 降级为离线分析工具，不进入控制器。

### 3.2 IP-10 · πIMU：没有 IMU 时，重建“事件定时器”

**动机（直觉）**：IMU 的核心价值是**高频变化检测**，不是绝对导航。接触、滑移、卡住、释放都是“变化”；只要能在对的时刻检测到变化，就不需要米/秒²的绝对精度。夹爪更是一个天然的“单自由度惯性传感器”：夹到物体时，开度响应会停在一个平台；夹空时，会一路到 0；滑移时，开度/腕部图像会出现高频抖动。

**形式化**：见 U16–U18。

**信号集**：

| 信号 | 估计方法 | 主要用途 | 失效模式 |
|---|---|---|---|
| `v_ee, a_ee` | EE 位置 Savitzky–Golay / Kalman 常数加速度模型 | 接触冲击、卡住（命令速度≠实际速度） | 位姿量化、未知 dt、30 Hz 混叠 |
| `ω_ee, α_ee` | 四元数/旋转矩阵对数差分 | 旋转类任务、插入对准 | rpy 奇异性、角度包裹 |
| `j_q` | 臂关节位置二阶差分，按关节限位归一化 | 关节冲击、碰撞 | 摩擦/死区 |
| `s_g, \dot s_g` | 夹爪开度及其差分 | 抓握占用、闭合速率 | 单自由度、无触觉 |
| `f_wrist` | 腕部图像相位相关/光流能量（高频带） | 滑移、接触振动、物体相对运动 | 遮挡、透明/弱纹理 |
| `e_base` | 头立体视觉自运动残差；`lower_body` 腰关节姿态代理 | 底座/躯干被人为扰动 | 视觉退化、腰关节命令运动混淆 |

**事件检测**：

- **接触开始**：`‖a_ee‖` 或 `f_wrist` 的高频能量在“命令速度低/接近零”时上升；用 CUSUM 或 HMM 变点检测，而不是裸阈值。
- **抓握占用（GIS）**：闭合命令后，检测 `s_g` 是否在 `s_empty + margin` 以上形成平台，并保持 W 步稳定。`GIS = (t_close, s_∞, σ_s, N_osc, τ_rise)`。这是本轮最可解释的信号。
- **滑移**：夹爪闭合且 EE 近似静止时，腕部图像中物体相对夹爪的运动 > 阈值；或 `s_g` 出现高频抖动。透明物体用边缘/深度线索兜底。
- **卡住**：命令速度 > `v_min`，实际 EE 速度 < `v_min/3`，且残差 `‖v_cmd − v_obs‖` 持续上升 W 步。
- **释放**：`s_g` 增加 > margin，且物体-腕部光流分离。
- **扰动**：头立体视觉自运动残差 > 阈值，且无法用 `action.pivot`/`lower_body` 的命令运动解释。

**离线 oracle 校准（关键）**：

- 数据集有 `timestamp`、`frame_index`、`state_torso`、`waist_state_joint`、`gripper_controls`、`recomputed_ee_valid`；这些在评测中**不可用**，但可以离线给事件打标签/验证。
- 用 `timestamp` 把“控制步”映射到秒，评估 πIMU 的定时误差；用 `state_torso`/`waist_state_joint` 做底座/躯干扰动的 oracle；用 `gripper_controls` 做夹爪命令的 oracle；用 `recomputed_ee_valid` 过滤坏 EE 位姿。
- 明确区分**离线 oracle 分析**与**在线可用信号**；论文/报告中必须分开写，避免误读为“读了 IMU”。

**未知 dt 的处理**：

- 接口无时间戳 ⇒ 差分单位是“控制步”。用稳健尺度（MAD）归一化；阈值用分位数而非物理单位；事件延迟以“控制步”报告。
- 若需要秒级预算，用 server 端 wall-clock 的 `get_action` 调用间隔 / 估计的执行步数做粗校准；这只是工程近似，不写进科学结论。
- episode 开头若干步因历史补齐会产生伪零加速度 ⇒ warm-up gate（前 W 步，建议 W=5）不触发。

**pilot 证据（示意，不是结论）**：

- 数据：`G1_Dex1_PlugInEthernet`，30 个 100 帧窗口（30 Hz），扫描到 7 次明显闭合事件。
- 夹爪平台：空夹 ≈ 0.13–0.14；疑似夹物 ≈ 0.57 / 0.61 / 1.11 / 1.18 / 2.81（Dex1 单位）。
- EE 加速度：episode 0 的前 100 帧（接近阶段，夹爪静止）原始二阶差分峰值 ~10.6 m/s²（噪声主导）；另一段 400 帧（帧 300–699，含夹爪闭合）Savitzky–Golay（窗 9、二阶）后峰值 ~1.24 m/s²、均值 ~0.1–0.2 m/s²；该段夹爪闭合时 EE 几乎不动 ⇒ 接触不一定在 EE 加速度上显形，夹爪平台更稳。
- 结论：先做“夹爪平台 + 腕部光流”的抓握/滑移事件，再做 EE 加速度事件；不要把 πIMU 当成 IMU 的精确复制。

**可验收**：E619/E621/E622。若接触/抓握 AUROC <0.80 或误报 >1/episode，则关闭事件触发，只保留 IP-02 的夹爪平台。

### 3.3 IP-11 · RIVL：需求-惯性验证环

**动机（直觉）**：机器人最常见的最后一公里失败不是“完全不会”，而是：

- 以为抓住了，其实夹空；
- 以为插到位了，其实只搭在口上；
- 以为挂住了，其实只是靠在钩子边；
- 以为拉链拉上了，其实卡在半途；
- 该停的时候不停，继续推/转，把本来能成功的状态推坏。

这些都可以用“验证”救：在宣告成功前做一个小测试；在事件触发时更新信念；在信念低且预算未尽时重试；在预算耗尽时安全退出。

**形式化**：见 U19–U24。

**决策循环**：

```
观测 o_t → NeedSpec 更新 r̂, H
         → πIMU 更新事件 E_t
         → 更新信念 b_t = P(φ=1 | o, r̂, E)
         → 若 b_t ≥ 1-δ：执行终态验证 T_φ；通过则 stop，失败则 retry/recover
         → 若 b_t 在不确定带 [δ_lo, 1-δ]：continue / 小验证
         → 若 b_t < δ_lo 且 n_retry < N_max：retry（改抓/改路径/改原语）
         → 若 t > τ_p 或 n_retry = N_max：recover（安全退出/保守放置）
```

**验证测试库**（按需求 `c/φ` 选）：

| 测试 | 适用 | 动作 | 通过条件 | 风险 |
|---|---|---|---|---|
| `T_grasp` | 抓取/搬运 | 抬升 5 mm，保持 300 ms | 物体随动（腕部视觉 + EE） | 物体滑落；低 |
| `T_insert` | 插入/卡扣 | 微退 2 mm，再轻推 | 阻力/座位保持（πIMU 残差） | 拔出已到位；低 |
| `T_release` | 放置/叠放 | 张开夹爪，退 1 cm | 物体保持稳定（腕部/头视觉） | 碰倒；中 |
| `T_arrange` | 整理/拼写 | 头相机看终态布局 | 与学习到的谓词匹配 | 视角遮挡；低 |
| `T_closure` | 拉链/袋子 | 轻拉/轻压 | 闭合状态视觉确认 | 拉坏；中 |
| `T_support` | 支撑/悬挂 | 轻撤支撑，观察 200 ms | 物体不掉 | 掉落；中 |

**Phase 1（MVP）只做被动验证**：`A_v = {continue, verify_*, retry, stop}`，不做主动探针。这样避免“探针扰动场景”的风险，也先证明“事件触发验证”本身有效。

**Phase 2（可选）主动探针**：`probe_push`（≤2 mm）、`probe_rotate`（≤5°）、`probe_lift`（≤5 mm）、`probe_retreat`（≤2 mm），全部满足 U23 安全包络，且只做一次；失败则回到探针前状态。

**与 chunk 的关系（合规修正）**：

- `action_chunk_size` 固定；不能运行时变长。验证测试通过“动作内容”实现：在 chunk 内安排“微退/轻推/抬升”的小动作，再回到策略；不改变数组长度。
- 需要高频反馈的相位，靠**全局更小的 T_a**（2/4）而不是运行时变长；T_a 的选择在提交前按任务簇/延迟预算决定。
- 验证测试必须平滑、有界，不制造延迟尖峰；πIMU/验证器与主策略并行，总新增延迟目标 ≤5 ms。

**可验收**：E623/E624/E625。若被动验证相对基线无显著提升，砍掉决策层，只保留 IP-09/IP-10 作为分析工具。

### 3.4 IP-02 修正：抓握验证从“三信号”升级为“平台 + GIS + 腕部视觉”

**原方案**：腕部几何 + 抓手标量 + EE 速度三信号，训练二分类器。  
**本轮修正**：

1. **夹爪平台是第一信号**：闭合命令后，`s_g` 是否停在 `s_empty + margin` 以上并稳定 W 步。空夹会到 ~0；夹物会停在物体宽度对应的平台。pilot 显示空夹 0.13–0.14 vs 疑似夹物 0.57–2.81，说明可分。
2. **GIS（Grip-Inertial Signature）**：闭合时间、平台值、平台稳定性、振荡次数、上升时间；用轻量分类器输出 `P(object present | GIS)`。
3. **腕部视觉交叉验证**：物体是否在指间、是否随夹爪闭合发生形变/位移；用于排除“夹到桌面/夹到线缆”等平台假阳性。
4. **抬升测试（可选，Phase 2）**：小抬升 5 mm，看物体是否随动；这是最可靠的抓握确认，但有滑落风险。
5. **介入准则**：只在 `P(not grasped) > 1-τ_conf`（高阈值）且 `n_retry < N_max` 时介入；否则不动。保持第 1 轮的高精度低召回原则。

**可验收**：E619。抓握占用 AUROC ≥0.85；空夹/夹物平台可分；误判 ≤2%。

### 3.5 IP-03 修正：固定 T_a 的合规工程形态

**原方案**：运行时按相位自适应 chunk 长度（U8）。  
**本轮修正**：

- `metadata.action_chunk_size` 固定；默认 **T_a=4**（30 Hz 下 ~133 ms 一块）；延迟吃紧或任务偏长程时用 **T_a=8**；接触密集任务可提交 **T_a=2** 的版本。不同 T_a 是**不同提交配置**，不是运行时变长。
- chunk 缝合（U7）保留：在固定边界做位置/速度连续；但必须先复刻官方 `run_client.py` 的执行语义，确认评测端是否自带插值/平滑；若自带，则缝合默认关闭。
- 延迟兜底（U12）保留：超预算返回安全延拓 + `degraded` 标记；审计看板导出 p50/p99、jerk、边界失配。
- 端口隔离：每个端口一个 policy 实例（Approach 1），或 server wrapper 按连接维护 session；`reset()` 零参，`get_action(obs)` 单参；共享后端必须并发安全。

**可验收**：E626/E628。固定 T_a 下 0 次 ACTION REJECTED；p99 ≤105 ms；N 端口 8 h 无串扰。

## 4. 符号与定义（U13–U25）

| 符号 | 含义 |
|---|---|
| `r` | 需求向量（U13） |
| `q_ψ(r \| ℓ, R_t)` | 需求后验（U14） |
| `H_t` | 需求歧义度（U15） |
| `z_t` | πIMU 特征向量（U16） |
| `E_t` | 事件过程（U17） |
| `GIS_t` | 夹爪冲激响应签名（U18） |
| `b_t` | 需求满足信念（U19） |
| `A_v` | 验证动作集（U20） |
| `U_v(a)` | 验证效用（U21） |
| `φ_stop` | 终态停止判据（U22） |
| `S_probe` | 探针安全包络（U23） |
| `T_a^0` | 固定 chunk 长度（U24） |
| `G` | 观测性缺口 / 信息价值（U25） |

**定义 U13（需求向量）**
`r = (ε_p, ε_o, c, τ_p, φ, s, β)`，其中 `ε_p ≥ 0` 为平移容差（m），`ε_o ≥ 0` 为姿态容差（rad），`c ∈ {free, contact, insert, rotate, deform, support}` 为接触 regime，`τ_p > 0` 为坚持预算（控制步），`φ ∈ Φ` 为终态判据，`s = (s_p, s_o, s_T)` 为探针安全包络（平移/旋转/时长），`β ∈ [0,1]` 为释放后支撑稳定性阈值。

**定义 U14（需求后验）**
`q_ψ(r | ℓ, R_t)`：由语言 `ℓ` 与检索到的示范统计 `R_t` 参数化的后验；输出 `r̂ = E_q[r]`。`ψ` 为轻量推断头（冻结 VLM 特征 + 小型 MLP/归一化流），不使用任务 id 查表。

**定义 U15（需求歧义度）**
`H_t = H[q_ψ(r | ℓ, R_t)] + λ·Var_norm(r)`，离散分量用熵、连续分量用归一化方差；`H_t` 高表示“这个任务的要求不确定”，应提高验证预算；`H_t` 低表示可以开环快跑。

**定义 U16（πIMU 特征）**
`z_t = Φ(o_{t-k:t}) = [v_ee, a_ee, ω_ee, α_ee, j_q, s_g, \dot s_g, f_wrist, e_base]`；所有差分按控制步定义，使用稳健尺度归一化（MAD），不做绝对物理单位声明。

**定义 U17（事件过程）**
`E_t = (e_t^contact, e_t^slip, e_t^jam, e_t^release, e_t^perturb) ∈ {0,1}^5`；每个事件由 CUSUM/变点检测器产生：
`C_t = max(0, C_{t-1} + ρ_t − ν)`，`e_t = 1[C_t > h]`，其中 `ρ_t` 是残差（如 `‖v_cmd − v_obs‖` 或腕部光流能量），`ν` 为漂移容差，`h` 为阈值。

**定义 U18（Grip-Inertial Signature）**
`GIS_t = (t_close, s_∞, σ_s, N_osc, τ_rise)`：闭合时间、平台开度、平台标准差、振荡次数、上升时间；`P(occ | GIS_t)` 为抓握占用概率。夹空 → `s_∞ ≈ s_empty`；夹物 → `s_∞ > s_empty + margin`。

**定义 U19（需求满足信念）**
`b_t = P(φ = 1 | o_{1:t}, r̂, E_{1:t})`，由轻量分类器/贝叶斯更新给出；事件似然 `P(E_t | φ)` 在离线数据上校准。

**定义 U20（验证动作集）**
`A_v = {continue, verify_grasp, verify_insert, verify_release, verify_arrange, retry, stop}`；Phase 2 追加 `{probe_push, probe_rotate, probe_lift, probe_retreat}`。

**定义 U21（验证效用）**
`U_v(a) = b_t(a) − λ_t·C_time(a) − λ_s·C_safe(a) − λ_l·C_lat(a)`；`b_t(a)` 是执行动作后的预期成功信念；`C_time`、`C_safe`、`C_lat` 分别为时间、安全、延迟成本；`λ` 由任务需求 `r` 调制（如插入任务更重视 `C_safe`，整理任务更重视 `C_time`）。

**定义 U22（终态停止判据）**
`φ_stop = 1[b_t ≥ 1−δ and T_φ passes]`，`T_φ` 是 U20 中与 `φ` 对应的验证测试；`δ` 默认 0.1，按任务校准。若 `b_t` 高但 `T_φ` 失败 → `retry`；若 `b_t` 低且预算未尽 → `continue`。

**定义 U23（探针安全包络）**
`S_probe = {|Δx| ≤ s_p, |Δθ| ≤ s_o, duration ≤ s_T, reversible}`；默认 `s_p = 2 mm`、`s_o = 5°`、`s_T = 300 ms`；只在 `c ∈ {insert, rotate}` 或 `φ` 为离散终态时启用。

**定义 U24（固定 chunk 长度）**
`T_a = T_a^0 ∈ {2,4,8}`，在提交前按任务簇/延迟预算选择，运行时不变；`metadata.action_chunk_size = T_a^0`。若组委会书面确认允许变长，才启用第 1 轮的 U8。

**定义 U25（观测性缺口 / 信息价值）**
`G = I(E; o_oracle | o_avail)`，其中 `o_oracle` 是离线 oracle（`state_torso`/`waist_state_joint`/`timestamp`），`o_avail` 是评测可用观测；`G` 是“多给这个信号能带来多少事件信息”的上界代理，用离线互信息/条件熵估计。

## 5. 推导（L8–L12、P1）

**引理 L8（非对称代价下的验证增益）**
设 `b = P(φ=1)`，`c_FP` 为“未完成却宣告成功”的代价，`c_FN` 为“已完成却继续执行”的额外时间/延迟代价，`c_V` 为验证代价。若验证完美：
- 立即停止的期望代价：`(1−b)·c_FP`；
- 先验证的期望代价：`c_V + (1−b)·c_FN`（若 φ=0，验证失败后继续，付出 `c_FN`；若 φ=1，验证通过后停止，无额外代价）。
故验证优于立即停止 iff
`c_V < (1−b)(c_FP − c_FN)`。
当 `c_FP > c_FN`（终态假阳性比多花时间更贵）且 `b` 不接近 1 时，验证有正收益。若验证不完美（灵敏度 `α`、特异度 `β_v`），条件变为
`c_V + (1−b)(1−β_v)c_FP + b(1−α)c_FN < (1−b)c_FP`，
即验证的误报/漏报也必须计入。∎

**引理 L9（无 dt 下的事件可检测性与尺度不变性）**
在变点模型下，设变点前后特征分布为 `P_0, P_1`，`D = KL(P_1‖P_0)`。CUSUM 的期望检测延迟满足 `E[delay] = O(log h / D)`（`h` 为阈值）。若特征先做稳健尺度归一化 `z' = (z − median)/MAD`，阈值取分位数，则检测器对全局时间尺度因子 `c > 0` 不变（因为只改变差分幅度，不改变归一化后的序关系）。因此 πIMU 可以在未知 dt 下做事件定时，但延迟只能以“控制步”报告，不能声称物理秒。∎

**引理 L10（需求条件化 vs 任务 id）**
设 `θ*` 为任务的最优行为参数（chunk/speed/retry/verification 等）。若存在映射 `M` 使 `θ* = M(r)`（即 `r` 是 `θ*` 的充分统计量），则 `r`-条件化至少不劣于 task-id 条件化；当 task-id 还携带 `r` 未覆盖的信息时，性能损失上界由条件互信息 `I(θ*; z_task | r)` 给出。故“需求向量”不是任务 id 的替代品，而是更可迁移的压缩；若 E620 显示 `r` 丢失了任务关键信息，应回退到 task token 或二者并用。∎

**引理 L11（探针安全界）**
设探针位移 `‖Δx‖ ≤ s_p`，系统在探针邻域内局部 Lipschitz（常数 `L`），且探针后有恢复动作把末端带回探针前状态（误差 ≤ ε_r）。则探针引起的状态偏差 `≤ L·s_p + ε_r`；对场景物体的非预期位移 `≤ 2(L·s_p + ε_r)`（往返各一次）。故 `s_p` 越小、恢复越快，安全界越紧；当 `L` 未知时，用离线数据估计经验上界，并取保守 `s_p`。∎

**引理 L12（验证延迟的可信度预算）**
若验证器与主策略并行，新增延迟 `≤ Δ`；主策略动作 jerk 上界为 `J_max`，验证动作由同一平滑策略生成且 jerk 上界同为 `J_max`，则 per-step 延迟 p99 增加至多 `Δ`，jerk p99 不高于 `J_max`。只要 `Δ` 在官方延迟预算内、且验证动作不引入离群值，可信度指标不会因验证而系统性恶化。若验证需要同步等待（非并行），`Δ` 可能远超预算 ⇒ 必须并行/预取/缓存。∎

**命题 P1（观测性缺口的信息价值，可检验）**
`G = I(E; o_oracle | o_avail)`。在离线数据上，用 `state_torso`/`waist_state_joint`/`timestamp` 作为 `o_oracle`，估计 `G` 与“πIMU 事件 AUROC 相对 oracle 的差距”。若 `G` 很小（如 <0.05 bit），则“再要一个 IMU”对事件检测的边际价值有限；若 `G` 很大，则应把“接口应暴露 IMU/躯干状态”作为对组委会的公共品建议。P1 不是定理，而是可证伪的实验设计（E629）。

### 6.1 需求推断（离线统计 + 在线轻量更新）

```python
class NeedSpec:
    """从语言 + 成功示范统计推断 r；不查 task-id 表。"""
    def __init__(self, demo_bank, vlm, head):
        self.bank = demo_bank          # 32 任务的离线统计（终态位姿、时长、夹爪平台、regime 标签）
        self.vlm = vlm                 # 冻结语言/视觉编码器
        self.head = head               # 小型 r 回归/分类头

    def offline_stats(self, task_demos):
        # 终态稳定窗口：释放后 0.5 s
        terms = [terminal_pose(d) for d in task_demos]
        eps_p = quantile([dist(p, median_pose(terms)) for p in terms], 0.9)
        eps_o = quantile([ang_dist(R, median_rot(terms)) for R in terms], 0.9)
        tau_p = max(1.0, quantile([duration(d) for d in task_demos], 0.9)
                         - median([duration(d) for d in task_demos]))
        c = classify_regime(task_demos)          # 规则 + VLM 分段
        phi = select_predicate(task_demos, c)    # 参数化终态谓词
        s = safe_envelope(task_demos)            # 低分位位移/旋转
        beta = release_stability(task_demos)
        return Requirement(eps_p, eps_o, c, tau_p, phi, s, beta)

    def infer(self, obs, language):
        R = self.bank.retrieve(language, k=3)    # 语言相似度，不查 task id
        r_prior = self.bank.weighted_stats(R)
        r_post = self.head.update(r_prior, self.vlm.encode(language), obs)  # 前 K 帧
        return r_post.mean, r_post.entropy()     # r̂, H
```

### 6.2 πIMU 事件观测器

```python
class PseudoIMU:
    def __init__(self, W=5, h=4.0, nu=0.5):
        self.W, self.h, self.nu = W, h, nu
        self.warm = 0

    def update(self, hist):
        # hist: 叠帧后的 obs（EE/夹爪/关节/腕部/头）
        self.warm += 1
        if self.warm <= self.W:
            return Events.none()                 # 首帧补齐的伪信号，不触发

        p = smooth_savgol(hist.ee_pos)           # 窗 9/二阶，或 Kalman
        v = deriv(p); a = deriv(v)
        w = quat_log_deriv(hist.ee_rot)
        j = second_diff(hist.arm_q)
        s = hist.gripper
        ds = deriv(s)
        f = wrist_flow_energy(hist.wrist_imgs)
        e = head_ego_residual(hist.head_imgs, hist.lower_body)

        # 夹爪平台：闭合后 s 稳定在 s_empty+margin 以上
        occ = plateau_detect(s, ds, s_empty=0.25, margin=0.20, steps=8)
        # CUSUM 残差：命令速度 vs 实际速度（卡住/接触）
        rho = norm(hist.cmd_vel - v)
        self.cusum = max(0.0, self.cusum + rho - self.nu)
        jam = self.cusum > self.h and norm(v) < norm(hist.cmd_vel) / 3
        contact = (norm(a) > q(a, 0.95) and norm(hist.cmd_vel) < v_eps) or (f > q(f, 0.95))
        slip = occ and (wrist_object_motion(hist.wrist_imgs) > q_slip) and norm(v) < v_eps
        release = ds > q(ds, 0.95) and s > s_empty + margin
        perturb = e > q(e, 0.99)
        return Events(contact, slip, jam, release, perturb, occ)
```

### 6.3 RIVL 控制器（Phase 1：被动验证）

```python
class RIVL:
    def __init__(self, need, pimu, verifier, base, tau_conf=0.9, delta=0.1):
        self.need, self.pimu, self.verifier, self.base = need, pimu, verifier, base
        self.tau_conf, self.delta = tau_conf, delta

    def reset(self):
        self.pimu.reset(); self.belief = None; self.n_retry = 0

    def act(self, obs, language):
        r, H = self.need.infer(obs, language)
        E = self.pimu.update(obs.hist)
        b = self.verifier.belief(obs, r, E)      # b_t = P(φ=1)

        # 1) 终态置信且预算允许：验证后再宣告成功
        if b >= 1 - self.delta:
            if self.verifier.test(obs, r.phi, E):     # T_grasp/T_insert/T_release/...
                return self.base.stop(obs)
            self.n_retry += 1

        # 2) 高置信“未完成”且预算未尽：重试/改抓/改原语
        if b < self.delta and self.n_retry < self.max_retry(r):
            self.n_retry += 1
            return self.base.retry(obs, r, E)

        # 3) 其余：继续原策略；需求歧义高时用短验证/保守动作
        return self.base.act(obs, r, E, H)
```

- **条件推进**：IP-01（等合规答复）、IP-04（等合规/算力）、IP-05（等 pivot 语义实测）。
- **暂存/砍掉**：IP-07、IP-12；若 E623 失败，IP-11 决策层砍掉；若 E621 失败，πIMU 事件砍掉，只保留夹爪平台。

---

## 11. 本轮最值得押注的创新点（一句话）

**押注 IP-10 + IP-11 的“被动验证”组合：它把缺失的 IMU 变成可解释的夹爪冲激响应/EE 事件定时器，再用需求向量决定“什么时候该验证、什么时候该停”，在不增加新硬件、不读取评测侧信息、不违反单模型/固定 chunk 合规的前提下，直接打在最后一公里的“以为做到了、其实没做到”上。**
