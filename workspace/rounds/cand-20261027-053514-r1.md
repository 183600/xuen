# 第 8 轮 · BEA：智能体是预算分配器，排行榜是任务组合，成本控制是可信延迟

> 检索/复核日期：2026-10-27（UTC）。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「智能体」「排行榜」「成本控制」。我先去核对规则，结果发现一个会改变整个优化目标的事实：官方参赛手册明确写的是「按 32 个任务的总平均成功率排序；成功率相同才看总平均步骤分；再相同看提交日期」——不是上一轮我以为的「成功率与步骤分综合排序」。同时每个任务跑 10 次（5 类泛化各 2 次），共 320 次真机试验，单次上限 180 秒。这个事实把本轮的主判断钉死了：**在成功率第一、步骤分只做平局裁决的排行榜上，最值得做的不是更大的 VLA，也不是继续抠步骤分，而是一个围绕单一 checkpoint 的「预算感知具身智能体」：用任务图/信念/风险估计决定何时花计算、何时验证、何时重试；用 32 个等权任务组成的「任务组合」分配数据与真机调试槽；用异步快慢调度把延迟和成本控制在可信范围内。** 上一轮 PILOT-GPR 的放置、少样本、产学研素材保留为组件，但「步骤分 59.7%」的预算逻辑被修剪。

## 0. 本轮先核实：规则变了，榜单仍是预览

### 0.1 排名规则：成功率第一，步骤分只做 tie-break

中文参赛手册（[S6]，2026-10-27 抓取）原文：

> 「实时榜单按 32 个任务的总平均成功率进行排序，成功率相同时按总平均步骤分排序，若仍相同，则提交日期较早的模型排序靠前。」

英文手册（[S7]）逐字对应：*"The real-time leaderboard is sorted by overall average success rate across all 32 tasks. In the event of a tie, the overall average step score is used as the differentiator. If still tied, earlier submission dates rank higher."*

这有三个直接后果：

1. **成功率的权重是 100%，步骤分只在完全打平时才生效。** 上一轮把「终局步骤占 39.8% 步骤分、放置类占 59.7%」当作预算分配的第一性依据，方向是对的（终局放置确实是成功闸门），但算术理由错了：不是因为它值 60% 的步骤分，而是因为它是 32/32 任务的最后一道成功闸门。步骤分现在只是“平局裁决 + 诊断工具”，不能再用它来论证 40% 的资源分配。
2. **32 个任务等权，每个任务占总分的 3.125pp。** 这是本轮最重要的“排行榜算术”：一个任务从 0% 提到 30%，总分 +0.94pp；提到 60%，+1.88pp；把 3 个“接近零”的任务提到 30%，总分 +2.8pp——这已经接近榜首与榜尾预览差距（9.2pp）的三分之一。反过来，在已经 50% 的任务上再抠 5pp，只值 0.16pp。**“抬地板”比“刷平均”更划算。**
3. **成功率是 320 次试验的宏平均，统计功效很低。** 每任务 10 次、每轴 2 次；单任务在 p=0.3 时的标准误约 14.5pp，总分的标准误约 2.56pp；两模型独立比较时，80% 功效只能检测约 10pp 的差异，配对设计（同场景）也只能检测约 7pp。**相邻名次的 1–2pp 差距基本是噪声，不能用来判断谁的方法更好。** 这直接决定了本轮的两个策略：不要追 1–2pp 的小修小补；把真机调试槽花在“能把某个任务从接近零抬到 30%+”的大效应上。

### 0.3 头部模型的方法与瓶颈：按公开资料，不按预览名次

预览表里的模型名对应的是真实公开模型家族；我按公开论文/模型卡逐个核对，得到的是“范式画像”，不是 UniBot 实测排名（表见产物区 §1.4）：

- **MolmoAct2（预览第 1）**：Ai2 的 action reasoning VLA，Molmo2-ER 空间/具身推理骨干 + flow-matching action expert；公开声称 3D 推理、“最高 37× 更快”、双臂任务无需逐任务微调；其 Molmo2-ER 骨干在 13 个具身推理基准平均 63.8/100（[S15][S16]）。它的强项是空间 grounding 与速度，弱点不在“看懂”，而在**接触丰富的最后一步**与长程恢复。
- **WALL-OSS-0.5（第 2）**：4B、部署导向的 VLA，3B VLM 骨干 + 动作组件，单阶段三源混合训练；公开声称在 17 个真机任务中有 4 个在零后训练下达到 80%+ 自主完成（[S17]）。强项是预训练即用的真机能力，弱点是**32 任务的覆盖广度**与细粒度放置。
- **DreamZero（第 3）**：World Action Model，视频扩散骨干，联合预测未来世界状态与动作；公开声称在未见环境上 62.2% 平均任务进度，是最佳预训练 VLA 基线（27.4%）的 2 倍以上（[S18]）。强项是物理/环境泛化，弱点是**推理成本**：视频扩散在 180s/远程 API/延迟可信度约束下很重。
- **spirit/VLAGO（第 4）**：Spirit-v1.5，Qwen3-VL-4B + DiT action head；公开声称 2026-01-11 在 RoboChallenge Table30 排名第 1，核心主张是“干净数据是机器人基础模型的敌人”（数据多样性）（[S19][S20]）。强项是真机基准与数据配方，弱点是**基准特定性**与五轴泛化。
- **DM0（第 5）**：embodied-native VLA，空间 CoT，Table30 Specialist 平均 62.0%，16×H20 训练（[S21]）。强项是专家任务与空间推理，弱点是**通才单模型**与 CoT 延迟。
- **π0.5（第 6）**：异构数据共训练的开放世界 VLA，多机器人 + 网页数据 + 高层语义预测（[S22]）。强项是语义/环境泛化，弱点是精确操作与长程恢复。
- **GigaBrain-0.7（第 7）**：三系统架构，统一理解/预测/动作，37,000+ 小时数据，把世界模型放进决策回路（[S23]）。强项是数据规模化与物理预测，弱点是**重**：训练与推理成本都高。
- **GR00T N1.5（第 8）**：双系统 VLA，VLM 骨干在预训练与微调中冻结；语言跟随率 46.6%→93.3%，总体成功率 43.3%→83.0%（GR-1 基准）（[S24]）。强项是快慢分离与语言跟随，弱点是冻结骨干的适应上限与精细操作。

共同瓶颈不是“语义理解”：这些模型在各自基准上都能看懂、能规划；到了 UniBot 的 32 任务、5 轴、真机、180s 场景，大家仍在 20–30%。**剩下的差距主要在最后一步的接触/精度、失败后的恢复、以及跨 5 轴的场景覆盖。** 预览前三是三种不同范式（action-reasoning VLA、deployment VLA、world action model），说明没有单一架构压倒性胜出；这反而支持“在现有 VLA 上做运行时可靠性”的性价比判断。

### 0.4 数据/接口：33k、v2、N 端口、延迟与变异性被记录

- 数据集仍是 32 个任务约 33k 条、169 小时；HangCup 实测 1,043 条 / 194,564 帧 / 30fps，`lastModified` = **2026-10-14**（[S10][S11]）。
- 提交接口仍是 v2（最近提交 2026-08-21，[S9]）：四路 RGB、双臂关节/EE 位姿、夹爪、下半身、单字符串 `observation.language`；`obs_delta_indices`、`image_resize`、`action_chunk_size` 由选手声明；`reset()` 每 episode 一次；joint/ee 二选一（[S8]）。
- 新读到的一条关键工程约束：评测在 **N 台机器人**上随机顺序运行，选手必须暴露 N 个连续端口（示例 N=3），每端口独立、状态隔离；平台会记录每步响应延迟及其变异性、动作的统计规律，并可能随成绩一起展示（[S8] §5–6）。这意味着**“延迟稳定性/动作规律性”本身是可信度的一部分**：一个时快时慢、偶尔 2 秒不返回的 agent，即使成功率高，也可能被标记为异常。成本控制因此不只是“平均快”，而是“可预测地快”。

### 0.5 新素材：Unitree Rehearsal 与 UnifoLM 的世界模型线

- **Unitree Rehearsal**（2026-10-22 发布，SCMP/TechTimes 报道，[S36][S37]）：让 AI agent 搜论文、写机器人控制代码、在仿真里测试、通过阈值再上真机，形成“自进化”回路；王兴兴称这是年度最重要的项目；报道同时指出，复杂物理接触任务（如堆叠不规则物体、折衣服）仍是当前机器人系统的失败点。这给本轮一个直接启发：**“智能体”最先能落地的形态可能不是运行时的大 LLM 规划器，而是离线地合成/测试确定性技能与恢复代码**——这既不违反单模型规则，又能把长尾失败变成可复用工具。
- **UnifoLM-ER-Flow**（[S13]）：在单一 VLM 里联合对齐视觉、语言、未来动态区域（光流 + VQ-VAE token）与离散动作；这是“世界模型作为辅助头”而不是“视频世界模型当策略”的轻量路线。**UnifoLM-WMA-0**（[S14]）是更重的世界模型线，模型卡当前受限；**UnifoLM-WLA-1.0-Base**（[S12]）是 6B、Apache-2.0、24GB 可微调的 VLA 底座。
- 这让我把“VLA / World Model / 混合”的选择提前定下来：**主路径是 VLA + 轻量辅助头（动态区域/锚点/风险）+ 确定性几何；世界模型只在离线数据生成或短时终端预演里用，不做全时视频 rollout。** 这既是成本控制，也是单模型合规。

## 1. 三个灵感词，各自钉到规则上

### 1.1 智能体：不是聊天规划器，是预算分配器

在 UniBot 里，“智能体”最容易被误解成“接一个 VLM 做高层规划”。但规则明确：所有任务用同一模型，不能混合多个模型（[S6][S7]）。所以运行时的“第二大脑”不可行，也不必要。真正可行的智能体形态是：

```text
单一 checkpoint（VLA + 若干轻量 head）
        +
确定性运行时（任务图、几何、检索、验证、恢复、调度）
```

它的核心决策不是“下一步做什么语义子任务”（这可以由公开评分步骤 + 指令匹配给出），而是**“在这一步，值不值得多花 100ms 计算 / 多花 3 秒重试 / 多花一次真机调试槽”**。换句话说，智能体是 **value-of-computation（VOC）分配器**：

- 状态：任务图节点、目标/容器/夹爪信念、人工干扰标志、剩余时间、已尝试动作、失败次数、模型置信度。
- 动作：快路径、标准路径、慢路径（更多去噪步/检索/锚点）、反事实放置、验证、恢复、放弃。
- 目标：在 180s 硬预算和延迟稳定性约束下，最大化 episode 成功概率；不是最大化每一步的“思考深度”。

这条路线与 2026 年的几条证据对齐：DIRECT 证明“何时/何地花测试时计算”比“统一加计算”更能改善成功–成本 Pareto（最高 65% 延迟下降，[S25]）；Learning Robot Metareasoning 把“计算预算 + 动作承诺长度”建成 SMDP，证明状态依赖的预算优于固定预算（[S26]）；Decoupled Early Exits 把 backbone 深度、action expert 深度、去噪步数变成三个可配置计算轴（[S27]）；SafeLoop 用风险预测 + 回滚在不改 VLA 参数的情况下降低不可逆失败（[S28]）。这些都不是“更大的模型”，而是“更会花计算/更会恢复的系统”——正是 UniBot 当前 20–30% 成功率最缺的东西。

### 1.2 排行榜：32 个等权任务组成的低功效实验

把排行榜当“分数榜”会误导；它更像一个 **32 臂的、每臂 10 次观测的、成功率先行的多臂老虎机**。

- 32 个任务等权：每个任务 3.125pp。所谓“提高平均成功率”，本质是“提高 32 个任务成功率的算术平均”。一个 0% 的任务是一个 3.125pp 的洞；一个 60% 的任务再提 10pp 只值 0.31pp。**边际收益在低成功率任务上最大**。
- 每任务只有 10 次，且 5 轴各 2 次：单任务估计的 95% 区间约 ±28pp；轴级也只有 64 次（每轴 20% 权重），不要指望从 10 次里读出“位置轴比背景轴差 5pp”这种结论。
- 总分 320 次：95% 区间约 ±5pp；两模型比较的最小可检测差异约 7–10pp。**相邻名次是噪声，榜首与榜尾的 9.2pp 才接近可检测边界。**
- 步骤分只在成功率完全相同时才生效。它不是“第二目标”，而是“平局裁决 + 诊断信号”。正确用法：用步骤分 − 成功率的差值找“差最后一步”的任务；不要用步骤分权重来分配训练预算。

因此“排行榜感知”的策略是：

1. **抬地板**：优先把 0–15% 的任务抬到 30%+，而不是把 50% 的任务抬到 55%。
2. **大效应优先**：只做预期 +10pp 级别的干预（验证/恢复、终端放置、任务级数据补齐）；不做 1–2pp 的微调，因为排行榜测不出来。
3. **配对评估**：同一任务、同一场景种子下做 A/B；用任务级 bootstrap，而不是看总分点估计。
4. **平局准备**：在成功率接近的集团里，步骤分是 tie-break；所以“验证/恢复”不仅提成功率，也会顺带提步骤分——但它是副产品，不是主目标。

### 1.3 成本控制：四层成本 + 延迟稳定性

UniBot 的“成本”至少有四层：

| 层级 | 成本 | 约束/证据 | 对本轮的含义 |
|---|---|---|---|
| 推理 | GPU、每步延迟、FLOPs | 远程 API；平台记录延迟与变异性 [S8] | 快慢路径、缓存、早退、批处理；p99 要稳 |
| 单集 | 180s 墙钟 | 官方规则 [S6] | 重试/验证要与进度竞争；长程任务限次数 |
| 评测 | 320 次计分真机 + 单任务调试槽 | 官方规则/平台 [S6][S8] | 调试槽是稀缺资源；用任务组合分配 |
| 数据/训练 | 33k 演示、169h、微调算力 | 数据集 [S10][S11] | 只补最弱任务；合成数据不主导；优先零梯度方法 |

第五层是隐性的：**延迟稳定性 = 可信度**。平台会把每步延迟、变异性、动作统计规律随成绩展示（[S8] §6）。一个“平均 80ms、偶尔 2s”的 agent 比“稳定 120ms”的 agent 更可疑。所以成本控制的目标不是“平均最快”，而是：

```text
在 p99 延迟 ≤ L_max、延迟方差 ≤ V_max、单集 ≤ 180s 的约束下，
最大化成功率；其次最小化平均计算/重试成本。
```

这直接推出**异步快慢调度**：快路径始终以稳定节奏返回 action chunk；慢路径（检索、候选评分、验证）在后台跑，结果只影响下一个 chunk；如果慢路径没准备好，快路径继续用旧计划，不阻塞。这样既拿到“慢思考”的收益，又不把延迟方差打爆。

## 2. 主判断：从“更大的 VLA”转向“更可靠的预算感知智能体”

### 2.1 头部模型的“最后一步”签名

预览表最值得注意的不是名次，而是**步骤分与成功率的差**：

| 模型 | 成功率 | 步骤分 | 差 |
|---|---:|---:|---:|
| MolmoAct2 | 29.7 | 39.0 | 9.3 |
| WALLOSS | 28.5 | 38.9 | 10.4 |
| DreamZero | 27.9 | 37.9 | 10.0 |
| spirit | 25.9 | 34.4 | 8.5 |
| DM | 23.5 | 31.7 | 8.2 |
| PI | 22.8 | 30.6 | 7.8 |
| GigaBrain | 22.6 | 29.5 | 6.9 |
| gr00t | 20.5 | 28.1 | 7.6 |

前三名的差是 9.3–10.4pp，后五名是 6.9–8.5pp。**如果**这张表的结构有哪怕一点点真实性，它说明：头部模型能把大部分步骤做完，但最后一步（放置/插入/闭合/倾倒）经常失败；而且越强的模型，越容易“走到最后再倒下”。这不是“语义不够”，而是“最后三厘米 + 失败后不恢复”。

这给了一个非常具体的经济学：如果头部模型能把“步骤分 − 成功率”这个差的一半转成完整成功，它的成功率会 +4.5–5pp——在 320 次试验里，这是接近可检测边界的大效应，足以改变名次。**验证/恢复/终端重试的杠杆，比再预训练一个更大的 VLA 更直接。**

### 2.2 为什么是现在：规则、数据、接口、模型生态都到位

- **规则清晰了**：成功率第一、步骤分 tie-break；320 次；180s；单模型。优化目标第一次可以写成明确的约束优化。
- **数据够了**：33k、每任务约 1k、四路相机、EE 位姿、5 条复述；足够训练风险/成功 critic、构建放置位姿库、做离线回放。
- **接口够了**：`obs_delta_indices`/`image_resize`/`action_chunk_size` 由选手控制；EE 动作空间可直接落位姿；`reset()` 明确每集清状态（[S8]）。
- **模型生态够了**：MolmoAct2 证明 action-reasoning VLA 可以又快又强；WALL-OSS 证明 4B 部署导向 VLA 可零后训练真机；ER-Flow 证明“动态区域辅助头”可以塞进单一 VLM；WLA-1.0 提供 Unitree 自家 6B 底座。
- **组织方向对了**：Unitree Rehearsal 明确把“agent 写代码 + 仿真验证 + 真机反馈”当作年度重点（[S36][S37]）；我们的“离线 agent 合成确定性技能”与它同向，但更聚焦比赛的单模型约束。

## 3. 方案轮廓：BEA-VLA

```text
语言（32×5 复述之一）
   │
   ▼
BSG：指令 → 任务 → 公开评分步骤图；当前步骤 s_t；谓词/权重
   │
   ├── 观测（4 相机 + 关节/EE + 夹爪 + 下半身）
   │        │
   │        ▼
   │   信念跟踪 b_t：目标/容器/干扰物位姿、夹爪、人工干扰、已尝试、剩余时间
   │        │
   │        ▼
   │   风险头 r_t：P(未来 H 步内失败 | b_t)；可恢复性
   │        │
   │        ▼
   │   VOC 控制器：在 {fast, std, slow, retrieve, cpa, verify, recover, abort} 中选
   │        │
   │        ├── fast/std/slow：同一 checkpoint 的不同计算档（去噪步/深度/视图）
   │        ├── retrieve：ICR 上下文（关系键 + 相位）
   │        ├── cpa：K 个候选放置 + 解析评分（稳定/容纳/碰撞/可达/朝向）
   │        ├── verify：缓放 + settle + 双谓词校验
   │        └── recover：nudge / regrasp / retry / rollback
   │        │
   │        ▼
   │   action chunk（稳定节奏；慢路径异步更新下一个 chunk）
   │
   ▼
RRL：谓词从 1→0（人工撤销/掉落/移动）→ 回退步骤 → 复用 BSG/CPA/ICR
```

一句话：**把公开评分步骤当骨架，把 33k 当记忆库，把风险触发的计算分配和验证/恢复当主武器，把 32 任务组合当资源分配器，把异步调度当延迟保险。**

## 4. 预期收益、可证伪点与风险

### 4.1 预期收益（分层，不打包票）

- **保守层（只做 RRL + BSG + 预算感知 ICR）**：把“差最后一步”的部分成功转成完整成功；如果终端步失败占失败的一半，目标 +3–5pp 总分。这是最稳的。
- **进取层（加 CPA + VOC）**：终端放置成功率 +10–15pp；按 q（到达终端步比例）0.4–0.7 折算，总分 +4–10pp。这是假设，不是承诺；必须用调试槽证伪。
- **成本层**：快路径覆盖 70–80% 的步，慢路径只在 20–30% 的高风险步触发；目标平均延迟不升、p99 稳定、单集不超 180s。若 VOC 只提升 1–2pp 却把 p99 翻倍，直接砍掉。
- **排行榜层**：抬 3 个最弱任务的地板，比刷 10 个强任务的平均更可能改排名；但 320 次试验的低功效意味着任何 <5pp 的增益都只能靠配对/离线证据，不能靠总分点估计。

### 4.2 可证伪点（先写死）

1. **H1 终端闸门**：若 T27（叠碗）/T10（插头）/T19（拉链）/T07（相框）调试槽里，RRL+CPA 对终端步成功率提升 <5pp，则“最后一步”假设不成立，回退到纯 BSG+ICR。
2. **H2 VOC 划算**：若风险-VOC 在同等平均延迟下不比“统一慢路径”成功率高，或 p99 超过预算，则砍掉 VOC，保留固定快慢两档。
3. **H3 抬地板**：若任务平衡训练 + TPA 选出的最弱 3 任务在配对调试里没有 +10pp，则 TPA 的边际收益假设不成立，回退到均匀调试。
4. **H4 单模型合规**：若主办方认定多 head/确定性工具属于“混合模型”，则把所有学习 head 合并进唯一 checkpoint，去掉任何外部学习工具；仍不确定就邮件确认。
5. **H5 统计**：所有主结论必须报告任务级 bootstrap 95% CI；若 CI 跨 0，不得写进“有效”。

### 4.3 风险与合规（先立后破）

- **单模型边界**：风险头/成功 critic/锚点头必须是同一 checkpoint 的 head；检索库是数据不是模型；验证/恢复是确定性代码。任何外部检测器（SAM/FoundationPose）只离线用于标注，不进推理。模型卡逐项披露。
- **外部数据**：手册只读到“官方 32 任务数据”，外部自采/实验室数据是否允许未确认；默认 OFF，邮件确认后再开。
- **跨 episode 记忆**：`reset()` 明确每集清状态；不做跨集自适应，避免“10 次独立运行”争议。只在单集内维护信念。
- **延迟变异**：异步慢路径 + 固定 chunk + 上限；慢路径未完成就用旧计划；监控 p99/方差；不做“有时 2s、有时 80ms”的突发计算。
- **调试槽稀缺**：每个大版本最多 1 槽；用 TPA 选任务；槽是发布门，不是调参器。
- **占位榜单**：预览数据只做弱先验；不根据预览名次做方法选择；等真实榜单/运行记录上线再重跑排行榜算术。
- **统计噪声**：预注册假设；配对场景；任务级 bootstrap；不追 <5pp 的点估计。
- **算力**：24GB 单卡可跑 6B LoRA + 快路径；慢路径/CPA 用 CPU/轻量几何；若延迟不达标，降级到 4B 底座或更少去噪步。

## 5. 一句话押注

**把单一 checkpoint 变成预算感知的具身智能体：用风险触发的计算分配、验证/恢复和反事实放置，把“差最后一步”的部分成功转成完整成功；用 32 任务地板而不是平均步骤分来分配数据与真机调试预算——这是本轮最值得押注的方向。**

### 1.2 320 次试验的统计功效

设任务 t 的成功率为 p_t，单任务 10 次，总分：

```text
S = (1/32) Σ_t (1/10) Σ_{a=1..5} Σ_{r=1..2} y_{t,a,r}
```

| 量 | 公式/假设 | 数值（p≈0.3） |
|---|---|---:|
| 单任务 SE | sqrt(p(1-p)/10) | 14.5pp |
| 单任务 95% CI | ±1.96×SE | ±28.4pp |
| 总分 SE | sqrt(p(1-p)/320) | 2.56pp |
| 总分 95% CI | ±1.96×SE | ±5.0pp |
| 两模型独立比较 MDE（80% power, α=0.05） | 2.8×sqrt(2p(1-p)/320) | ≈10.1pp |
| 两模型配对比较 MDE（ρ=0.5） | 2.8×sqrt(2p(1-p)(1-ρ)/320) | ≈7.2pp |

**结论**：官方 320 次试验只能可靠检测 **7–10pp** 级别的差异；单任务 10 次只能看“有没有”，不能看“差多少”。因此：

- 不要用总分点估计判断 1–2pp 的方法优劣；
- 主实验要用配对场景 + 任务级 bootstrap；
- 真机调试槽要花在预期 +10pp 的大效应上；
- 排行榜相邻名次（预览里 0.2–2.4pp）基本是噪声，不能反推“头部方案为什么强”。

## 2. 目标函数与排行榜算术

### 2.1 形式化

```text
y_{t,a,r} ∈ {0,1}        # 任务 t、泛化轴 a、重复 r 的成功
S = (1/32) Σ_t (1/10) Σ_a Σ_r y_{t,a,r}     # 排行榜主指标
P = (1/32) Σ_t (1/10) Σ_a Σ_r p_{t,a,r}     # 步骤分，tie-break
rank = sort by (S desc, P desc, submit_date asc)
```

权重：

| 单位 | 权重 | 含义 |
|---|---:|---|
| 单次试验 | 1/320 = 0.3125pp | 任何一次成功/失败对总分的影响 |
| 单任务 | 1/32 = 3.125pp | 一个任务全部 10 次的总权重 |
| 单轴（全局） | 1/5 = 20% | 每轴 64 次试验（32 任务×2） |
| 单任务单轴 | 2/320 = 0.625pp | 每任务每轴 2 次，噪声极大 |

### 2.2 任务地板与边际增益

| 干预 | 总分增益 | 备注 |
|---|---:|---|
| 1 个任务 0%→30% | +0.94pp | 3.125×0.30 |
| 1 个任务 0%→60% | +1.88pp | 3.125×0.60 |
| 3 个任务 0%→30% | +2.81pp | 接近榜首-榜尾 9.2pp 的 1/3 |
| 全部 32 任务 +1pp | +1.00pp | 广谱小增益 |
| 1 个任务 50%→55% | +0.16pp | 边际递减 |
| 1 个任务 50%→80% | +0.94pp | 仍不如抬 0% 任务 |

**结论**：在成功率第一的排行榜上，**“把接近零的任务抬到 30%”比“把强任务从 50% 刷到 55%”更划算**。这与“终局放置是成功闸门”并不矛盾：终局放置是跨任务的广谱杠杆，任务地板是任务级的资源分配；两者相乘——先用终局恢复把“差最后一步”的任务救回来，再用 TPA 把调试/数据预算压到最弱任务上。

### 2.3 统计功效与最小可检测差异

| 场景 | n | p | SE | 95% CI | MDE（80% power） |
|---|---:|---:|---:|---:|---:|
| 单任务 | 10 | 0.3 | 14.5pp | ±28.4pp | —（太小） |
| 单轴 | 64 | 0.3 | 5.7pp | ±11.2pp | ≈16pp（独立） |
| 总分 | 320 | 0.3 | 2.56pp | ±5.0pp | ≈10.1pp（独立）/≈7.2pp（配对 ρ=0.5） |
| 单任务 + 诊断槽 20 次 | 20 | 0.3 | 10.2pp | ±20.1pp | ≈29pp（独立） |

**解读**：

- 官方总分只能看大效应；不要用 320 次去证明 +2pp。
- 单任务 10 次不能做任务级因果；只能做“有没有成功”的描述。
- 调试槽即使 20 次，单任务也只能看 ~30pp 的大效应；所以调试槽要用来验证“终端步是否从 20% 到 50%”这种大跳跃，而不是微调。
- 配对设计（同场景种子）能显著降方差；这是我们在离线/调试槽里必须坚持的。

### 2.4 Rank-aware 目标与 checkpoint 选择

不要只最大化 E[S]；在低功效排行榜上，更稳的目标是：

```text
maximize  E[S]  -  λ · SD(S)          # 风险厌恶
或        maximize  P(S ≥ S_target)    # 达到目标分数
或        maximize  LCB_{10%}(S)      # 下置信界，避免“点估计高、方差大”
```

实践：

- 用任务级 bootstrap（32 个 cluster）估计 S 的分布；选 **10% 分位数** 最高的 checkpoint，而不是点估计最高的。
- 预注册“主指标 = S；次指标 = P；诊断 = 终端步成功率/步骤分差”。
- 如果两个 checkpoint 的 S 差异 < MDE，视为统计上不可区分；用更便宜/更稳的那个（成本控制）。

### 2.5 步骤分的正确用法

步骤分不是第二目标，但有两个正当用途：

1. **tie-break**：成功率接近的集团里，步骤分决定名次；RRL/CPA 在提成功率的同时会提步骤分，是“顺带”收益。
2. **诊断“差最后一步”**：步骤分 − 成功率的差，近似“部分完成但未成功”的质量；差值大的任务/模型，优先做终端验证/恢复。预览前三的差值 9.3–10.4pp 是这一诊断的弱先验。

**不要**再用“步骤分占 59.7%”来论证 40% 的训练预算；那是上一轮的错位。

### 3.2 BSG：信念-步骤图

**图结构**：每任务一个线性图 `s0 → s1 → … → s_k`，节点来自官方 `score_steps`，权重 w_i；边上挂谓词集合。指令匹配用 32×5=160 条复述 + 中文映射 + 嵌入兜底。

**信念状态**：

```python
b_t = {
  "task_id": int,
  "step_id": int,
  "step_text": str,
  "step_weight": float,
  "predicates": dict,          # e.g. {"cup_on_rack": 0/1, "gripper_closed": 0/1}
  "target_pose": (x,y,z,quat) | None,
  "container_pose": (x,y,z,quat) | None,
  "distractor_poses": [...],
  "gripper": {"left": float, "right": float},
  "human_flag": bool,          # 大光流/目标位移/遮挡
  "attempts": int,
  "failures": int,
  "time_left": float,          # 180 - elapsed
  "confidence": float,         # 模型自评/动作方差
}
```

**信念从哪来**：

- 目标/容器位姿：优先用头双目的立体几何 + 颜色/形状分割（确定性，无第二个模型）；未见物体失败时，用 VLA 的 pointing/anchor head 输出的 2D 点 + 深度反投影；再失败则用上一帧/演示先验。
- 夹爪：proprio 直接给。
- 人工干扰：比较连续帧的大光流区域与目标区域；目标位姿突变 > 阈值 → `human_flag=True`；同时记录“旧位姿”，用于撤销后的恢复。
- 谓词：SSG 的步骤谓词 + 几何检查（相对位姿、接触、容纳、闭合）；模型 success critic 作为第二票。

**为什么不做跨 episode 记忆**：`reset()` 明确每集清状态（[S8]）；规则说“10 次独立运行”。跨集自适应会引入公平性争议，默认不做；只在单集内维护 `attempts/failures/human_flag`。

### 3.3 风险头

**目标**：预测“未来 H 步内会失败/需要干预”，以及“当前失败是否可恢复”。不是预测任务成功（太稀疏），而是预测**局部风险**。

**特征**（低维、可解释、便宜）：

| 组 | 特征 |
|---|---|
| 模型不确定性 | K 个动作 chunk 的方差；快/慢路径动作差异；动作 token 熵 |
| 谓词/进度 | 当前步已耗时 / 演示中位时长；谓词未满足；夹爪闭合但物体未抬起 |
| 视觉 | 目标/容器位移；大光流；遮挡比例；腕部相机可见性 |
| 历史 | 本步失败次数；本集重试次数；上次恢复是否成功 |
| 任务先验 | 任务难度（Easy/Medium/Hard）；是否终局步；步骤权重 |
| 预算 | 剩余时间；长程任务标志 |

**标签**：

- 未来 H 步内是否发生“谓词回退/物体掉落/人工撤销/超时”；
- 终端步是否失败；
- 失败是否在 N 次重试内可恢复（可用 NRB/扰动回放近似）。

**训练/校准**：

- 小 MLP/逻辑回归（输入 <50 维）；类别不平衡用 focal loss/重采样。
- 用 isotonic regression 校准概率；报告 AUC + Brier。
- 保守阈值：宁可多触发一次 verify，也不要在高风险终端步“盲放”；但 verify 的成本要计入 VOC。
- 风险头是同一 checkpoint 的 head；如果工程上不方便，先用确定性规则（谓词未满足 + 时间/失败次数）做 v0，再换学习头。

### 3.4 计算动作集与成本

| 动作 | 做什么 | 额外延迟（目标） | 额外算力 | 预期收益 | 触发条件 |
|---|---|---:|---:|---|---|
| `fast` | 1–4 去噪步 / 浅层早退 | ~0 | 1× | 基线 | 低风险、简单步 |
| `std` | 8–16 去噪步 | +50–150ms | 2–4× | 小 | 默认 |
| `slow` | 16–32 去噪步 + 多视图 | +150–400ms | 4–8× | 中 | 高风险、终端步 |
| `lang` | 3–5 条复述集成/选一条 | +1–3 次前向 | 3–5× | 语言鲁棒 | 指令歧义/低置信 |
| `view` | 头/腕视图选择 + 裁剪/放大 | +10–50ms | 1.2× | 空间 grounding | 终端放置/遮挡 |
| `retrieve` | ICR top-K 上下文 | +20–80ms | 1.5× | 动作先验 | 罕见任务/高风险 |
| `cpa` | K 候选放置 + 解析评分 | +100–300ms | 5–10× | 终端成功 | 接近终端、风险高 |
| `verify` | 缓放 + settle + 双谓词 | +0.5–1.5s 机器人时间 | 1× | 发现失败 | 释放后 |
| `recover` | nudge/regrasp/retry/rollback | +2–5s 机器人时间 | 1× | 恢复 | 已验证失败 |
| `abort` | 提前停止 | - | - | 省时/防损 | 不可恢复/超时风险 |

**注**：延迟/算力是设计目标，不是实测；必须在本地压测后填真实值。所有慢动作都要有硬上限，超时回退 `std`。

### 3.5 VOC 控制器（SMDP / contextual bandit）

**单步 VOC**：

```text
VOC(a | b_t) = ΔP(success | b_t, a) - λ_T · τ(a) - λ_C · c(a) - λ_R · Risk(a | b_t)
a* = argmax_a VOC(a | b_t)     if max VOC > 0
   = std                       otherwise
```

- `ΔP` 由风险头/成功 critic 估计；没有可靠估计时用保守先验（例如 `cpa` 只在终端步 + 风险 > 阈值时给正价值）。
- `τ(a)` 是墙钟延迟；`c(a)` 是 FLOPs/GPU 成本；`Risk` 是碰撞/掉落/损伤风险。
- `λ_T` 要跟 180s 预算挂钩：剩余时间越少，λ_T 越大；`λ_C` 是成本控制的旋钮。

**SMDP：计算预算 + 动作承诺长度**：

```text
动作 = (a, T)   # a: 计算档；T: 本次返回/承诺的 chunk 长度
成本 = T·Δt_exec + τ(a)
收益 = P(成功 | b_t, a, T) - P(成功 | b_t, std, T0)
选择 argmax 收益 - λ·成本
```

这直接借用 Learning Robot Metareasoning 的 SMDP 形式（[S26]）：慢计算需要更长的开环承诺，反馈频率下降；控制器要在“更好的计划”和“更长的盲走”之间权衡。UniBot 的 `action_chunk_size` 固定，但我们可以用“固定 chunk + 异步慢路径”近似：慢路径在后台算，若在 chunk 结束前完成就用于下一 chunk；否则下一 chunk 继续用旧计划。这样不需要改接口，也能实现 SMDP 的“等待/不等待”决策。

**训练**：

1. 离线收集：用 base policy 在不同计算档（fast/std/slow/retrieve/cpa）下跑 33k 演示的 replay + 扰动；记录状态特征、动作、结果、延迟、重试。
2. 拟合：小 MLP 的 Q/advantage；或用上下文 bandit 的 IPS/doubly robust。样本量小，优先保守（CQL/保守回退）。
3. 影子模式：前 N 个 episode 只记录控制器的选择，实际执行 `std`；比较反事实收益，校准后再启用。
4. 安全包络：`recover` 只能在“已验证失败 + 剩余时间 > 阈值 + 无碰撞风险”时触发；`abort` 只能在“不可恢复 + 时间/损伤风险”时触发。
5. 在线校准：只用调试槽的少量数据调偏置/阈值，不重训大模型。

**为什么不是“统一慢路径”**：统一慢路径会把平均延迟/p99 拉高，且对简单步没有收益；VOC 的目标是“把计算花在刀刃上”，在同等成功率下降低成本，或在同等延迟下提高成功率。若实验证明统一慢更好，就砍 VOC——这是可证伪的。

### 3.6 异步快慢调度与延迟稳定性

**问题**：平台记录每步延迟与变异性（[S8] §6）；如果 agent 有时 80ms、有时 2s，会被视为异常；同时 180s 预算下，慢计算不能阻塞机器人。

**设计**：

```text
主线程（快路径）:
  every chunk:
    obs = latest_obs
    plan = latest_plan or default_plan
    chunk = policy_fast(obs, plan)     # 稳定 30Hz
    return chunk

后台线程（慢路径）:
  if risk > θ or step is terminal:
    plan' = retrieve/cpa/slow(obs, b_t)
    latest_plan = plan'                # 只影响下一 chunk
  else:
    idle
```

- 快路径永远有输出；慢路径的结果是“下一个 chunk 的建议”，不是“当前 chunk 的阻塞”。
- 慢路径有硬超时（例如 300ms）；超时就丢弃，下一轮再试。
- 每个端口独立状态；共享后端批量推理；N 端口并发用队列/批处理，避免互相阻塞。
- 延迟目标：p50 稳定、p99 ≤ L_max、方差 ≤ V_max；在调试槽记录真实分布，不靠猜。

**成本控制**：慢路径只在 20–30% 高风险步触发；CPA 只在终端步；检索有缓存；语言集成只在指令歧义时。这样平均成本接近 `std`，但把计算集中在最值钱的地方。

### 3.7 RRL：风险感知验证/恢复循环

```python
def act_and_verify(step, obs, b, policy, budget=2):
    for attempt in range(budget + 1):
        a = voc.select(b)                      # fast/std/slow/retrieve/cpa
        for chunk in policy.stream(obs, b, a):
            send(chunk)
            if b.predicates_met(step):
                break
        if not b.predicates_met(step):
            b = b.update(obs, reason=diagnose(step, obs))
            continue
        release_slowly()
        if stable(obs, window=0.5) and b.predicates_met(step):
            return True
        if b.recoverable(step, obs):
            b = b.with_recovery(nudge_or_regrasp(step, obs))
        else:
            break
    return False
```

**双谓词**：

- 几何谓词：相对位姿、接触、容纳、闭合、插入深度；
- 模型谓词：success critic / 步骤分类器；
- 两者都过 → 前进；一过一不过 → verify；都不过 → recover。

**恢复动作库**：

| 失败型 | 恢复 |
|---|---|
| 放偏/没对准 | nudge（小推/轻压）或 CPA 换候选 |
| 掉了/滑了 | regrasp → 重新放置 |
| 人工移动目标 | 更新信念 → 重新定位 → 继续当前步 |
| 人工撤销（叠好又拿走/拉链拉开） | 回退 step → 重新执行 |
| 碰撞风险 | rollback 到安全 waypoint（SafeLoop 式，[S28]） |
| 不可恢复/超时风险 | abort（保时间/防损；成功已丢，但避免更糟） |

**预算**：普通任务 ≤2 次；长程任务（T16/T17/T31）≤1 次；总时间守卫；每次恢复都计入 VOC 成本。

### 3.8 CPA：反事实放置智能体

**目标**：把“放置”从“policy 输出一个位姿”升级为“生成 K 个候选 → 解析评分 → 选最好 → 执行 → 验证 → 换下一个”。

**候选生成**：

```text
H_i = (T_B^R)^{-1} · T_B^G(t_release)      # 演示 i 的容器系释放位姿
H̄ = median_i(H_i)                          # 稳健中心
候选 = {H̄, H̄ + δ_j}                       # δ_j ~ 残差分布/±1cm/±5°
```

- 来源：OPT 库（每任务每步骤的容器系释放位姿 + 容差 τ_task）。
- 对堆叠：中心对齐 + 接触面法向；对插入：轴向对齐 + 深度；对悬挂：钩/孔对齐；对闭合：拉链/盒盖轨迹。

**解析评分**：

```text
Score(H) = w1·Stability + w2·Containment + w3·CollisionFree
         + w4·Alignment + w5·Reachability + w6·Visibility
```

| 项 | 检查 |
|---|---|
| Stability | 支撑多边形/质心投影；堆叠接触面积；倾覆角 |
| Containment | 目标在容器边界内；间隙/深度 |
| CollisionFree | 接近路径扫掠体 vs 障碍/容器壁；用双目点云 |
| Alignment | 朝向与目标轴/槽位对齐；插入轴误差 |
| Reachability | IK 可行、关节限位、可操纵性 |
| Visibility | 腕部相机能否看到接触点；遮挡 |

**执行**：

1. 选 Score 最高且 > 阈值的候选；
2. 先到 pre-place 位姿，再慢速伺服；
3. 缓放 + settle + verify；
4. 失败则换下一个候选（最多 K 次或预算内）；
5. 所有候选都失败 → 回退 policy 原始动作/重抓。

**为什么可行**：OPT 的位姿统计已有（33k 演示 + EE 位姿）；解析评分是确定性代码，无第二个模型；CPA 只在终端步触发，成本可控；它直接攻成功闸门。**风险**：透明/布料/小件几何不稳 → 分桶回退到 policy/ICR；评分权重靠启发式 → 用离线成功/失败片段校准。

### 3.9 TPA：32 任务组合评估器

**问题**：单任务调试槽稀缺；32 个任务都要估计；总分是宏平均。怎么花调试槽最值？

**模型**：每个任务一个 Beta 后验 `p_t ~ Beta(α_t, β_t)`；先验来自离线估计（弱）。每次调试一个任务，观测 k 次成功/失败，更新后验。

**分配规则（Thompson sampling）**：

```python
for each slot:
    for t in tasks:
        p_t_sample = sample(Beta(α_t, β_t))
        gain_t = (1/32) * max(0, min(1, p_t_sample + δ_t) - p_t_sample)
        # δ_t = 该任务可实现的提升（来自步骤分差/终端步风险/与目标差距）
        value_t = gain_t - cost(slot)
    choose argmax value_t
    run debug; update Beta
```

- `δ_t` 可用“步骤分 − 成功率”的差、终端步失败率、或与目标分位的差距估计；没有数据时用保守常数（如 0.1–0.3）。
- 停止条件：预算用完，或所有任务的后验 CI 足够窄。
- 输出：最弱任务列表 + 下一步数据/训练/调试建议。

**为什么是“排行榜感知”**：它直接优化“总分增益/调试成本”，而不是“平均测试所有任务”；在 320 次低功效、调试槽稀缺的设定下，这是更合理的资源分配。**风险**：先验/δ 估计错 → 用保守值 + 定期均匀抽检；不要完全 exploitation。

### 3.10 与单模型规则的兼容性

| 组件 | 合规处理 |
|---|---|
| 风险头/成功 critic/锚点头 | 同一 checkpoint 的 auxiliary heads，随主模型一起提交/部署 |
| VOC 控制器 | 轻量 head 或确定性规则；若学习，作为同一 checkpoint 的 head |
| 检索库 | 数据（演示片段/缓存编码），不是第二个模型；模型卡披露 |
| CPA | 确定性几何 + OPT 统计；无学习模型 |
| RRL | 确定性控制；无学习模型 |
| 外部检测器（SAM/FoundationPose） | 只离线标注/训练；不进推理 |
| 跨 episode 记忆 | 不做（`reset()` 每集清状态） |
| 运行时 LLM 规划器 | 不做（违反单模型/增加延迟） |

**若主办方判定多 head 也算“混合模型”**：退化为“单 head 多任务”（动作 + 辅助损失），风险用确定性规则，CPA/RRL 保留（代码不是模型）；仍不确定就邮件确认。

### 4.2 多 head 设计

| head | 输出 | 损失 | 用途 |
|---|---|---|---|
| action | flow-matching chunk | L_flow | 主动作 |
| step | 当前步骤完成概率 | BCE | BSG 推进/回退 |
| risk | 未来 H 步失败概率 | BCE/focal | VOC 触发 |
| critic | 终端成功概率 | BCE/ranking | VOC 价值 |
| anchor | 2D 目标/容器点（可选） | 热图/回归 | 信念/CPA |
| flowaux | 未来动态区域 token（可选） | VQ-VAE/CE | FlowFocus 辅助 |

**原则**：所有 head 共享主干；总参数量增加 <5%；推理时可按需跳过（head 很轻）；不引入第二个大模型。

### 4.3 计算感知训练

**v0（最简）**：可变去噪步数。

```text
训练：D ~ {1,2,4,8,16} 随机；同一 batch 用不同 D；
      加 consistency loss：低 D 输出逼近高 D 输出（stop-grad）。
推理：VOC 选 D；fast=1–4，std=8–16，slow=16–32。
```

**v1（进阶）**：backbone/action expert 早退（Decoupled Early Exits，[S27]）。

- 在 backbone/action expert 中间层加 Exit Transformer；
- 蒸馏最后一层；
- KV cache 合成，允许 action expert 比 backbone 更深；
- 推理时三轴（V, A, D）联合配置。

**v2（替代）**：recurrent-depth / latent refinement（RD-VLA，[S30]）。

- 迭代 action expert/ latent reasoning；
- 自适应停止（latent 收敛）；
- 优点：常数内存、可扩展计算；缺点：架构改动大。

**建议**：先做 v0（1–2 周可落地），v1/v2 只在 v0 显示“计算档有收益”后再投入。

### 4.4 FlowFocus 辅助头（可选）

**动机**：ER-Flow 证明光流动态区域可以作为单一 VLM 的辅助监督（[S13]）；对 UniBot 的终端放置/人干扰，动态区域能提示“哪里在动/哪里是交互主体”。

**做法**：

- 离线用光流提取动态区域 → VQ-VAE token；
- 加一个轻量 head 预测未来动态区域 token；
- 推理时用预测区域做腕部相机裁剪/视觉 token 加权（不生成视频）；
- 只在终端步/人干扰时启用。

**收益假设**：提高目标/容器 grounding，减少背景/干扰物影响；成本低（一个轻量 head）。**风险**：光流在透明/布料/小件上不稳 → 分桶；不要让它主导训练。

### 4.5 损失与课程

```text
L = L_flow
  + λ1 L_step        # 步骤谓词 BCE
  + λ2 L_risk        # 风险 BCE/focal
  + λ3 L_critic      # 终端成功 BCE/ranking
  + λ4 L_distill     # 可变 D / 早退一致性
  + λ5 L_anchor      # 可选 2D 锚点
  + λ6 L_flowaux     # 可选动态区域
```

| 阶段 | 数据 | 目标 | 退出条件 |
|---|---|---|---|
| 0 | 真实 33k | 复现底座 | 真实 held-out 不降 |
| 1 | + 任务平衡/终端加权 | 宏平均/地板 | 最弱任务不降，总分不降 |
| 2 | + 步骤/风险/critic 标签 | 谓词/风险可用 | 谓词 F1/风险 AUC 达标 |
| 3 | + 可变 D/蒸馏 | 计算档有收益 | fast 掉点 <3pp，slow 有增益 |
| 4 | + NRB/扰动 | 恢复/终端 | 终端步 +5pp（离线配对） |
| 5 | + VOC 离线 | 计算分配 | 同等延迟下成功率不降 |
| 6 | + 调试槽校准 | 真机 | 终端步 +10pp（目标） |
| 7 | + TPA/最终 | 全量 | 计分跑稳定 |

**任务平衡采样**：每个 batch 先均匀采任务，再在任务内采样；按运行成功率给最弱任务 1.5–2× 权重；不要完全放弃强任务（会伤平均）。

### 5.3 离线回放/扰动协议

**目的**：在不烧真机槽的情况下做相对比较；不追求绝对成功率。

1. 从 33k 演示中取初始帧/中间帧（按步骤边界切）。
2. 在回放/轻量仿真中执行策略；接触丰富步用 MuJoCo/Isaac 或真实片段拼接。
3. 扰动：
   - 位置：目标/容器 ±5–15cm；
   - 干扰物：路径旁插入 1–3 个刚体；
   - 背景：换桌布颜色/纹理（图像编辑）；
   - 未见物品：换同类不同色/形状的 mesh/texture；
   - 人为干扰：按官方 human 备注做 1-DOF 平移/撤销。
4. 每个条件用相同种子；配对比较；任务级 bootstrap。
5. 只信“相对排序/大效应”；绝对成功率以调试槽为准。

**协议**：

- 每个任务先跑 base vs BEA 的配对 A/B（同场景种子，10–20 次/边，若槽允许）。

### 5.5 统计协议

- 预注册：主指标 S；次指标 P；诊断终端步/步骤分差。
- 配对：同任务/同场景种子；任务级 cluster bootstrap（32 个任务）。
- 报告：点估计 + 95% CI；不写“显著”除非 CI 不跨 0。
- 多比较：Bonferroni/Holm 或预注册少量主假设。
- 选择：LCB（10% 分位）最高的 checkpoint，而非点估计最高。
- 功效：官方 320 次只能看 7–10pp；<5pp 的结论只作“方向性”，不作“有效”。

## 6. 成本模型与预算守卫

### 6.1 符号

```text
N        # 每个 episode 的决策步数
c_fast   # 快路径单步算力/延迟
p_slow   # 高风险步比例（VOC 触发慢路径）
Δc       # 慢路径相对快路径的额外成本
c_ret    # 检索/CPA/验证的额外成本（按触发率折算）
T_ep     # 单集墙钟（≤180s）
C_ep     = N·(c_fast + p_slow·Δc) + c_ret
C_succ   = C_ep / S                    # 每次成功的成本
```

### 6.2 成本–成功率的盈亏平衡

如果成功率从 S 提升到 S+ΔS，允许的成本倍率：

```text
C_succ' < C_succ  ⇔  C_ep' / (S+ΔS) < C_ep / S
                  ⇔  C_ep' / C_ep < 1 + ΔS/S
```

示例（**假设数字，仅用于决策口径**）：

| 场景 | S | ΔS | 允许成本倍率 | 解读 |
|---|---:|---:|---:|---|
| 保守 | 0.25 | +3pp | 1.12× | 成本最多 +12%，否则每次成功更贵 |
| 进取 | 0.25 | +5pp | 1.20× | 成本最多 +20% |
| 终端 | 0.30 | +10pp | 1.33× | 成本最多 +33% |
| 只提步骤分 | 0.25 | 0 | 1.00× | 不提高成功率的花费都是纯成本 |

**结论**：VOC 的价值不是“让每一步更快”，而是“让花出去的计算产生足够的 ΔS”。如果慢路径只让步骤分好看、成功率不动，按上表就是纯亏。

### 6.3 延迟预算

- 单集 180s，假设有效决策 300–900 步：每步平均预算 200–600ms（含机器人执行，不只是推理）。
- 快路径必须稳定在 chunk 周期内（例如 30Hz chunk = 33ms/步；实际以控制频率为准）；慢路径异步，不阻塞当前 chunk。
- p99 目标：不超过快路径周期的 2–3 倍；方差目标：p99/p50 ≤ 2.5（示例阈值，需实测校准）。
- 慢路径硬超时 300ms（可调）；超时丢弃，下一 chunk 再试。
- 单集时间守卫：剩余 <20s 时禁止 `retrieve/cpa/slow`，只允许 `fast/std/verify/abort`。

### 6.4 评测/调试成本

| 资源 | 数量/约束 | 分配 |
|---|---|---|
| 计分 trials | 320/次 | 只用于最终验证，不调参 |
| 单任务调试 | 未知，稀缺 | TPA 选最弱/终端任务；每大版本 ≤1 槽 |
| 离线回放 | 33k 演示 + 扰动 | 主要相对比较；不追绝对成功率 |
| 训练算力 | 24GB 单卡（目标） | 6B LoRA / 4B 全参谨慎；CPA/RRL 用 CPU |
| 人工 | 1 人 | 先做 P0，P1 只看门控 |

### 6.5 预算守卫（代码级）

```python
class BudgetGuard:
    def __init__(self, t_max=180.0, slow_ms=300, reserve=20.0):
        self.t_max, self.slow_ms, self.reserve = t_max, slow_ms, reserve

    def allow(self, action, t_left, risk):
        if t_left < self.reserve and action in {"slow","retrieve","cpa"}:
            return False
        if action == "recover" and t_left < 10.0:
            return False
        if action == "cpa" and risk < 0.4:
            return False
        return True
```

**原则**：预算守卫是硬约束，VOC 是软优化；任何学习控制器都不能绕过守卫。

## 8. 风险、合规与失败模式

| 风险 | 概率 | 影响 | 缓解 | 触发/放弃线 |
|---|---|---|---|---|
| 单模型定义不允许运行时工具/多 head | 中 | 高 | 学习组件同一 checkpoint；工具确定性；模型卡披露；邮件确认 | 若被拒 → 单 head + 规则风险 + 保留 RRL/CPA |
| 外部/实验室数据不允许 | 中 | 中 | 默认 OFF；只用官方 33k；L2L 开关 | 若拒绝 → 删 L2L，数据多样性用官方扰动 |
| 跨 episode 记忆被质疑 | 低 | 高 | 不做；`reset()` 清状态；单集信念 | 若规则允许再开 |
| 延迟变异被标记/惩罚 | 中 | 高 | 异步 + 硬超时 + p99 守卫；不做突发计算 | p99 >3× p50 → 降级慢路径 |
| 调试槽不足 | 高 | 高 | TPA 选任务；离线配对；一槽多用 | 只剩 1 槽 → 只验终端步 |
| 计算资源不足 | 中 | 中 | 4B 底座；LoRA；fast/std；CPU 几何 | 24GB 跑不动 6B → 换 4B |
| 透明/布料/小件几何失败 | 高 | 中 | 分桶；CPA 回退 policy；ICR；不硬做 | 连续失败 → 该任务只用 policy |
| 人干扰误判 | 中 | 中 | 大光流 + 位姿突变 + 旧位姿；保守触发 | 误触发多 → 提高阈值 |
| 统计噪声误导 | 高 | 高 | 预注册；配对；任务级 bootstrap；LCB | CI 跨 0 → 不作结论 |
| 预览榜单是占位 | 已发生 | 中 | 只作弱先验；等真实数据 | 真实榜单上线 → 重跑算术 |
| 规则更新 | 中 | 高 | 每周复核手册/公告；保留合规开关 | 规则变 → 重跑目标函数 |
| 安全/碰撞 | 低 | 高 | 力/电流阈值；rollback；abort；速度限制 | 任何损伤风险 → 立即 abort |

**合规声明（拟）**：

> 本方案只提交一个模型 checkpoint。动作、步骤、风险、critic、锚点等 head 共享同一主干并在同一 checkpoint 内导出；检索库为演示数据缓存，CPA/RRL/调度为确定性控制代码，不含额外学习模型。若主办方对“单模型”有更严格定义，我们将在提交前调整为单头多任务，并移除任何可能被视为独立模型的组件。

### 9.1 最值得写的三条（如果只能保留三个）

1. **BEA/VOC + 异步调度**：这是“智能体 + 成本控制”两个词的交点，也是与“更大 VLA”最清晰的差异化。
2. **RRL + CPA 的终端成功闭环**：这是“排行榜成功率第一”下最直接的可回收质量；预览步骤分差是弱先验。
3. **TPA 任务组合 + 任务地板**：这是“排行榜”这个词的真正含义；在 320 次低功效下比刷平均更合理。

### 9.2 不建议单独作为创新点

- “用世界模型做 VLA”：DreamZero/GigaBrain 已强，且成本高；本赛题 180s/远程 API 不适合全时 rollout。
- “更大的 VLA/更多数据”：33k 下边际收益不确定，且算力/时间不够；不如做运行时可靠性。
- “端到端 RL”：真机采样成本高、sim2real gap 大；本周期不碰。
- “每任务一个模型/LoRA”：直接违反单模型规则。
- “跨 episode 记忆”：`reset()` 与独立运行规则冲突。

## 10. 修剪清单（明确不做什么）

| 修剪项 | 原因 |
|---|---|
| 步骤分加权预算（上轮 59.7% 逻辑） | 规则是成功率第一，步骤分只 tie-break；预算应看成功率地板/边际增益 |
| 全时视频世界模型 / WMA-0 进主路径 | 推理成本/延迟与 180s、远程 API、延迟可信度冲突；只离线用 |
| 每任务 LoRA / 多模型集成 | 违反“同一模型、不得混合多个模型”；集成也可能被视作多模型 |
| 全 32 任务高保真数字孪生 | 数据/时间不够；用官方回放 + 轻量扰动 + 少量真机槽 |
| 运行时仿真/MPC | 延迟、模型误差、工程复杂度；不如几何 + 学习策略 |
| 仿真 RL 主训练 | sim2real gap；33k 演示 + 监督/辅助损失更稳 |
| 跨 episode 记忆/自适应 | `reset()` 每集清状态；10 次独立运行；公平性争议 |
| 单独的运行时 LLM/VLM 规划器 | 单模型规则 + 延迟 + 成本；BSG 已提供步骤骨架 |
| 统一 test-time scaling（每步都慢） | DIRECT 证明自适应分配更优；统一慢会拉高 p99 且无差别收益 |
| 额外相机/传感器 | 观测接口固定四路 RGB + proprio；不改硬件 |
| 推理时 SAM/FoundationPose 等外部模型 | 可能被视为第二个模型；只离线标注/训练 |
| 无限重试 | 180s 硬上限；重试与进度竞争；预算守卫 |
| 追排行榜 1–2pp 的微调 | 320 次 MDE 7–10pp；统计上看不见 |
| 用预览榜单名次反推方法优劣 | 数据是占位/脚本生成；只能做弱先验 |

## 12. 开放问题（需官方确认/实测）

### 12.1 必须邮件确认（影响方案合规）

1. **单模型边界**：同一 checkpoint 的多 head（动作/步骤/风险/critic/锚点）是否算“同一模型”？确定性几何/检索/恢复代码是否允许？检索库是否算“数据”而非“模型”？
2. **外部数据**：是否允许自采/实验室/仿真/网络视频数据？若允许，是否需要申报/同等公开？官方 33k 之外的数据能否用于预训练/微调？
3. **跨 episode 记忆**：`reset()` 是否要求完全清空所有状态？是否允许同一任务 10 次运行之间共享统计（非参数）？
4. **调试槽**：单任务不计分测试的次数/时长/预约方式？是否提供日志/视频/成功判定？能否用于 A/B？
5. **N 端口**：正式评测的 N 是多少？端口分配/重启/并发策略？是否允许共享后端批处理？
6. **步骤分**：具体公式？失败是否给部分分？是按 run 平均还是按任务平均？tie-break 时是否用同一批 320 次？
7. **配对**：不同模型是否在相同场景种子/初始状态下评测？runs 页面是否会公开 per-run 结果？
8. **延迟**：延迟/变异性是否用于排名/惩罚/异常检测？阈值是多少？慢路径是否会被标记？
9. **模型权重**：能否使用 Unitree WLA/ER-Flow/WMA-0 的公开权重？许可/申报要求？
10. **人干扰**：哪些任务/轴会触发？是脚本化还是真人？是否可检测/可恢复？
11. **动作空间**：joint/ee 是否都可？是否允许自定义阻抗/速度/夹爪力？是否有安全限制？
12. **提交限制**：每天/总共多少次提交？按最好成绩还是最新成绩排名？是否可撤回？

### 12.2 必须实测（影响成本模型）

- 快/慢路径的真实 p50/p99/方差（本地 + 远程 API）。
- N 端口并发的吞吐/排队/状态隔离。
- 180s 内实际可执行的决策步数/动作 chunk 数。
- CPA 几何在透明/布料/小件上的失败率。
- 风险头的真实 AUC/校准（离线→真机漂移）。
- 恢复动作的碰撞/损伤风险（安全包络）。
- 调试槽的单任务噪声（10/20 次的实际方差）。

### 12.3 需要等真实榜单

- 真实 per-task/per-axis 成功率；真实步骤分公式；真实头部模型的终端步失败率。
- 真实排名差距是否支持“相邻名次是噪声”的判断。
- 预览表的“步骤分−成功率”结构是否在真实数据中复现。
- 真实 N、真实延迟记录、真实人干扰频率。

## 13. 一句话押注

**把单一 checkpoint 变成预算感知的具身智能体：用风险触发的计算分配、验证/恢复和反事实放置，把“差最后一步”的部分成功转成完整成功；用 32 任务地板而不是平均步骤分来分配数据与真机调试预算——这是本轮最值得押注的方向。**
