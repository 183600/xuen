# 第 52 轮（承接第 51 轮 v15；灵感循环第 7 轮；本轮灵感：通用机器人 × 数据质量） · CoStride-PROVENANCE：可移植能力契约 × 数据质量包络 × 能力边界证书（v16）

> 承接第 51 轮 v15 CoStride-PIVOT。v15 用计划骨架证书把安全从"动作级"抬到"策略级"，用运行时能力下界 `A_lb` 与关节交付证明把安全从"抽象力矩"压到"真实关节"，并把重规划纳入实时可调度性。但它仍隐含两条未被点破的承重假设：**H13：通用性 = 任务/环境分布可被离线认证数据充分覆盖——只要把已见过的场景都认证过，就能"通用"地放行**。**H14：数据质量只影响性能，不影响安全——`M_derate`、JDA 阈值、PFV 判据、EDR 预测都是"已经学好的模型"，其训练数据的好坏被当作实现细节**。两个灵感词精确命中：**通用机器人**要求安全对象从"某个本体的某条任务"变成**可跨本体移植、可组合、并对未知任务显式拒绝的可移植能力契约**；**数据质量**要求安全从"模型正确"再下沉一层到**数据可信**——因为守卫的三个信任锚（`A_lb`、JDA、`τ_rp` 的模型）全都是数据的函数。二者耦合出一个更隐蔽、且会伪装成"高准确率"的致命悖论：**越通用的机器人，越要跑在其认证数据最稀疏的地方；而最能填补这些空缺的部署数据，恰恰因为未经审计而不能用来更新守卫**——若为了"通用"把部署数据直接喂给守卫模型，得到的是被数据泄漏与分布漂移掏空的**假 soundness**。于是 v16 把"数据"提升为一等公民：用**分层质量下界 `Q_lb`** 取代总体均值，用**数据契约与血缘**分离"学习数据"与"认证数据"，用**能力边界证书**把"通用"重新定义为"可证明的拒绝 + 安全退化"，用**组合泛化证书**把无界任务分布压缩成有界证书代数。

## 0. 直觉与动机

**灵感 1（通用机器人 → 证书必须可移植、可组合，并以"能力边界"而非"任务清单"定义安全）**
直觉：给专用机器人做认证，可以一条任务一条任务地覆盖；但"通用"意味着任务分布是开放、对手式、且不断增长的，**你永远不可能枚举完**。正确对象不是"已认证任务集合"，而是两条更小的东西：**(a) 组合代数**——新任务多由已认证技能组合而成，只要证明组合前置（接口兼容、热/捕获预算可加、不变量保持）成立，就能从子证书合成父证书；**(b) 能力边界**——对组合不出来、或落在认证支撑集之外的请求，机器人必须有**可证明的拒绝与安全退化**（退到已认证原语/保护姿态/人工接管），而不是"尽力而为"。因此"通用"不等于"无所不能"，而是**知道自己不能在哪、并能安全地停在那里**。这把通用性从"覆盖"变成"边界 + 代数"。

**灵感 2（数据质量 → 守卫模型也是数据的函数，脏数据直接侵蚀信任锚）**
直觉：v15 的估计-保证二分（学生用 `A_est`、守卫用 `A_lb`）防的是**模型误差**，却防不住**数据污染**：`A_lb` 的降额表、JDA 的残差/延迟阈值、PFV 的证伪判据、EDR 的漂移预测，全都是在某批数据上拟合/标定出来的。如果那批数据有标签噪声、校准过期、覆盖偏斜、甚至被投毒，那么"下界"可能根本不在真实能力之下，"故障检测率 100%"可能只是没测到那类故障，**信任锚会在最安静的地方断裂**。数据质量的第一原则不是"平均指标高"，而是**按分层（本体/任务/环境/工况）求下界**：总体 99% 干净可以掩盖某个安全关键层的 60% 脏。第二原则是**学习/认证防火墙**：用来训练学生的数据可以脏（只降可用性），用来给守卫定界的数据必须独立审计、来源可溯、且与被测模型不同源——否则就是**认证泄漏**（训练集被当测试集、标签由同一策略生成），得到的是自我印证的假通过。

**灵感 3（耦合 → 通用性-安全悖论与认证泄漏）**
直觉：通用机器人会跨本体、跨任务、跨环境地采集海量数据，看起来"数据越多越安全"。但真正决定 soundness 的不是数据总量，而是**单位任务上的认证证据密度**与**该证据的可信度**。任务越新，认证数据越稀；而机器人在部署中最想用来更新守卫的，正是这些"新但未审计"的数据。若直接把部署数据回灌守卫，就会同时发生两件坏事：分布漂移让旧的 `Q_lb` 失效，认证泄漏让新的"验证"失真。正确解法不是"少采集"，而是**把数据分成两条管道**：`D_learn`（探索/蒸馏/EDR 预测，可脏、可快、只影响可用性）与 `D_cert`（独立审计、来源链完整、分层覆盖、对抗样本齐备、只用于守卫与再认证）。二者之间是一道**血缘防火墙**，跨管道使用即 fail-closed。

**灵感 4（通用机器人 × 提议-处置 → 学生可用脏数据，守卫只用认证数据）**
直觉：v15 的"乐观学生 / 保守守卫"正好可以复用到数据层：学生与探索策略可以用 `D_learn` 快速提议"这个新任务能做、这样组合可行、这里值得探索"，但守卫必须用 `D_cert` 支撑的模型复核"该任务落在能力边界内、组合前置成立、质量下界达标"。学生被脏数据带偏只会导致更多拒绝与回退，**不导致放行未认证动作**。这把"数据质量"从一句工程口号变成与"估计-保证"同构的**第二重不对称**。

**灵感 5（数据质量 × 原型证伪 → 证伪对象新增"数据本身"）**
直觉：PFV/LFF 过去证伪的是策略与包络模型；v16 必须能证伪**数据管道**：投毒、标签噪声、校准过期、分布漂移、血缘伪造、组成拆分（把一条危险长任务拆成两条看似安全的短任务以绕过组合前置）。只有精确证伪器能定罪 `Q_lb` 越界；而"验证集准确率很高"绝不是证据，反而可能是泄漏的症状。JDA/EDR 的失败样本要按**数据层归因**回灌，区分"模型错"与"数据错"。

**灵感 6（通用机器人 × 关节驱动 → 跨本体迁移是能力归一化 + 迁移态射，不是盲目 sim2real）**
直觉：一个契约若绑死在某个本体的关节命令上，就谈不上通用。正确做法是把任务表达为**能力资源需求**（可达、负载、精度、速度、续航、捕获力矩），再由**迁移态射**把源本体的证书映射到目标本体；映射只有在目标本体的 `A_lb` 覆盖映射后的需求、且传感器/执行器语义保持不变量时才被接受。否则不是"迁移失败要调参"，而是**拒绝迁移、要求重新认证**。这把 v15 的 XFER 从"估计传输缺口 δ"升级为"证明态射存在且保不变量"。

**耦合升级**：v15 九层（L0 驱动 + L1–L4 决策通道 + …）之上新增贯穿全栈的 **数据治理纵向通道（DQE/DLAT/ACQ）** 与 **通用性纵向通道（PCC/CBC/CGC）**；联合状态扩为 `z=(x_r,x_h,x_e,κ,a_drive,d)`（`d`=数据/证据状态：血缘哈希、质量下界、认证覆盖密度）；JCPS 联合输出追加 `π_comp`（组合方案）与 `K_cert`（当前能力边界）。v16 不推倒 v15；它是给 v15 的两个"纸面信任锚"（数据可信、通用可覆盖）装上真实的证书与防火墙。

## 1. 形式化定义（增量：定义 95–102）

**定义 95（能力归一化契约与迁移态射）**
任务契约 `κ` 在通用机器人上不再直接是关节空间命令，而是**能力资源需求向量** `need(κ)=(reach,payload,precision,speed,endurance,τ_capture,…)`；本体 `e` 的认证能力 `A_lb^e(t)` 经归一化映射 `ν_e` 得到可满足域 `N_e={need: ν_e(A_lb^e)⊒need}`。**迁移态射** `φ_{e→e'}` 把 `κ` 从 `e` 搬到 `e'`，当且仅当：`N_{e'}⊇need(κ)`、存在保持传感器/执行器语义的映射 `φ`、且 `φ` 保持 `κ` 的不变量（接触约束、捕获域、边界）。不满足则 `reject('no_sound_morphism')`，禁止用目标本体的乐观估计强行迁移。证书随 `(κ, e, φ)` 三元组钉版本，而非随单个本体。

**定义 96（能力边界与已知-未知监控）**
`K_cert⊆Task×Z` 为已认证能力域，`ρ_cov(τ)` 为任务族 `τ` 的**认证覆盖密度**（有效认证证据/单位任务体积，按分层计）。运行时监控 `nov(z,τ;D_prov)` 给出相对认证支撑集的**新颖度**。**能力边界门** `CB(z,τ)` 放行当且仅当 `nov≤ν_max ∧ ρ_cov(τ)≥ρ_min`；否则进入**认证拒绝** `Refuse(τ)`：退化到已认证原语/保护姿态/人工接管，并记录未知样本。红线：`nov` 与 `ρ_cov` 禁止用总体均值；必须按分层给下界，且拒绝路径本身必须被认证（拒绝不能是新的不安全动作）。

**定义 97（分层数据质量包络）**
证据数据集 `D` 按分层 `s∈S`（本体/任务/环境/工况/故障类型）划分，质量元组 `Q(D)=(prov,cov,fresh,label,adv,balance)` 分别表示来源可溯性、分层覆盖、时效性、标签可信、对抗通过、类别均衡。构造**认证质量下界** `Q_lb(D)⊑Q_true(D)`（逐层、保守、绝不高估），与**乐观质量估计** `Q_est(D)⊒Q_lb(D)`（供学生/主动采集）。守卫模型的可用性条件是 `Q_lb(D_cert)≥q_min`（逐层支配）。`Q_lb` 构造器带版本哈希 `h(Q)`，与 `h(A)`、`h(D)` 一同钉入守卫。红线：`Q_lb` 禁止用总体平均、禁止由被审模型自评、禁止用未经独立审计的数据估计自身质量。

**定义 98（数据契约、血缘与学习/认证防火墙）**
每批证据 `D` 携带签名血缘链（标定→采集策略→变换→存储→使用）与数据契约 `DC=(scope, quality_floor, lineage_hash, retention, allowed_uses)`。合法使用当且仅当：血缘链有效、`h(D)=DC.lineage_hash`、`use∈DC.allowed_uses`、`Q_lb(D)⊒quality_floor`。**防火墙**：`D_learn`（学生/蒸馏/EDR 预测/探索）与 `D_cert`（守卫/再认证/PFV 判据）血缘不相交；`overlap(h(D_learn),h(D_cert))≠∅` 即判定**认证泄漏**并 fail-closed。模型版本必须钉住其认证数据血缘哈希 `h(D_cert)`，数据更新触发再认证，旧版本候选一律拒。

**定义 99（质量条件化可靠性）**
v14/v15 定理中的每个失效项现在都条件于数据质量：`α_act(A_lb;Q_lb(M_derate))`、`α_del(JDA;Q_lb(D_cert))`、`α_plan(PSC;Q_lb(Exit))`、`α_replan(CRT;Q_lb(τ_rp 标定))`，并新增 `α_data`（数据管道失效）与 `α_gen`（能力边界漏检）。若某守卫模型的 `Q_lb<q_min`，则其对应 `α` **不可声明**，该模型不得进入守卫——不是"α 变大"，而是"证书无效"。这把"数据质量"从软指标变成 soundness 的**硬前提**。

**定义 100（组合泛化证书与组合代数）**
已认证技能证书 `c_1,c_2` 的组合 `c_1⊕c_2` 可被认证，当且仅当**组合前置**成立：(i) 接口兼容（上游出口=下游入口，状态/坐标系一致）；(ii) 资源可加且不超预算（热负载、捕获力矩预算、时间预算按最坏环境走法相加）；(iii) 不变量保持（边界、屏障、PFL、捕获域在拼接处不被破坏）。前置成立则 `c_1⊕c_2` 继承子证书并附**组合见证** `w=(c_1.id,c_2.id,pre)`；不成立则必须 `re_certify`，禁止把长任务拆成短任务后"各自安全便整体安全"（组成拆分歧义）。这把无界任务分布压缩为"有界证书代数 + 运行时前置复核"。

**定义 101（认证价值与主动采集）**
区分**学习价值**（提升策略性能）与**认证价值**（缩小某分层的质量缺口或扩大守卫模型的认证覆盖）。主动采集按认证价值排序：`target=argmax_{gap∈Gaps(K_cert,Q_lb)} cert_value(gap)`，探针轨迹本身仍受 v15 守卫约束（不能为了采集数据而进入未认证危险区）。采集必须带血缘；未经审计的部署数据只能进 `D_learn`，要进 `D_cert` 必须经过独立审计/对抗复核/分层标注，构成**数据入证门**。

**定义 102（通用性-安全悖论与认证覆盖度量）**
任务族 `τ` 的通用性度量为 `Gen(τ)=(support(τ), ρ_cov(τ), Q_lb(τ), comp_depth(τ))`，**不得**压成单一平均精度。核心推论（通用性-安全悖论）：当 `support(τ)` 增长而认证证据不增长时 `ρ_cov(τ)` 单调下降，若仍以"已验证任务数"宣称安全，则安全会随通用性**静默退化**。因此放行规则强制：`ρ_cov(τ)<ρ_min ⇒ 只能监督/降级运行`；通用性提升必须由认证覆盖与质量下界同步背书，而非由"更多任务跑通"背书。

## 2. 新增产出与既有 IP 升级

**IP-96 PCC（Portable Capability Contract）**：能力归一化契约 + 迁移态射 `φ` + 不变量保持证明；跨本体迁移是认证动作，不是调参。
**IP-97 CBC（Competence Boundary Certificate）**：认证能力边界 `K_cert` + 已知-未知监控 + 认证拒绝/安全退化；把"通用"定义为"可证明的拒绝"。
**IP-98 DQE（Data Quality Envelope）**：分层质量下界 `Q_lb` + 乐观估计 `Q_est` + 版本 `h(Q)`；守卫只用逐层达标的 `D_cert`。
**IP-99 DLAT（Data Lineage & Attestation）**：签名血缘链 + 数据契约 + 学习/认证防火墙 + `h(D)` 钉版本；认证泄漏即 fail-closed。
**IP-100 CGC（Compositional Generalization Certificate）**：组合代数 `⊕` + 组合前置 + 组合见证；不满足前置即重认证。
**IP-101 ACQ（Active Certification Query）**：认证价值驱动的主动采集 + 数据入证门；探索受守卫约束。

**既有 IP 升级**
IP-93 ACC：`A_lb` 构造器的 `M_derate` 必须由 `D_cert` 标定且 `Q_lb≥q_min`；降额表更新走数据入证门与再认证。
IP-94 JDA：残差/延迟/跟踪阈值与故障注入集必须绑定 `D_cert` 血缘；检测率按分层报告，不用总体均值。
IP-91 PSC：骨架节点的技能必须携带 CGC 组合见证；节点先过能力边界门。
IP-92 CRT：重规划触发新增"新颖度过阈/认证覆盖不足/数据质量漂移"三类；OOD 下 `τ_rp` 可能更大，提前量按上界放大。
IP-95 EDR：漂移预测可用 `D_learn`，但其再认证证据必须来自 `D_cert`；数据陈旧导致的模型衰减也算漂移。
IP-89 KDX：学生可用 `D_learn`（可脏）提议；守卫只用 `D_cert` 支撑的模型；分歧仍只降可用性。
IP-90 LFF：场景生成器可学习自 `D_learn`，但 PFV 判据必须独立且基于 `D_cert`，禁止生成器与判据同源。
IP-83 PFV：新增数据层证伪（投毒/标签噪声/校准过期/漂移/血缘伪造/组合拆分）；证伪 `Q_lb` 与 `M_derate`。
IP-84 XFER：δ 升级为迁移态射认证；跨本体数据质量分层报告。
IP-77 DDA：十源 → **十二源**（+数据、+泛化/能力边界）。
IP-61 DCL：质量感知；采集认证缺口样本、血缘、认证泄漏样本；主动采集。
IP-62 CCA：新增数据投毒、标签噪声、校准过期、血缘伪造、OOD 规避、组合拆分红队。
IP-51 CAR：守卫加"`Q_lb≥q_min` ∧ `h(D)` 匹配 ∧ 能力边界内 ∧ 组合见证有效"。
IP-45 总线：新增 data-provenance / data-quality / competence / composition 话题。
IP-75 ASC：抽象选择条件于认证覆盖与质量下界；覆盖不足强制细化/降级。
IP-74 HTD-Cert：分解节点必须可组合（带 CGC 见证）且落在能力边界内。
IP-72 RRP：e-process 纳入质量下界、血缘、能力边界、组合见证证据；跨层仍带 δ。
IP-76 CCL：CCL++ 追加数据/泛化事件（入证、拒绝、泄漏、漂移），仍只追加。

## 3. 算法骨架

每个宏周期：
1. 读目标、证书 `C_t`、租约、`CCL++`、契约 `h(κ_c)`、包络 `h(A)`、**数据 `h(D_cert)`/`h(Q)`**；任一失效、血缘不匹配或质量下界不达标 → fail-closed。
2. L0 采集驱动状态，构造 `A_lb`（守卫）与 `A_est`（学生），记录 `ρ_a`、`h(A)`；JDA 交叉校验交付健康，阈值绑定 `D_cert`。
3. **数据治理**：从数据总线读入候选证据，DLAT 校验血缘/契约/用途；`D_learn` 进学生/蒸馏/EDR，`D_cert` 进守卫/再认证；检测认证泄漏即隔离。
4. HTD-Cert 展开为计划骨架 `G`，节点标注交互/步态/决策/环境分支与预置出口；**每个节点先过能力边界门 `CB` 与组合见证检查**。

**正确性定理（Portable, Data-Attested, Competence-Bounded Soundness）**
假设 (A1)–(A15) 承接 v15，且每个 α 项按其数据来源重新条件化。新增：**(A16)** 所有守卫模型满足 `Q_lb(D_cert)⊒q_min`，`D_learn` 与 `D_cert` 血缘不相交（无认证泄漏），`h(D)`/`h(Q)` 被守卫强制校验，未审计数据不得进入守卫；**(A17)** 能力边界监控以概率 ≥1−α_gen 检出 `nov>ν_max` 或 `ρ_cov<ρ_min` 的请求，且 `Refuse(τ)` 路径本身在 `A_lb` 下认证；**(A18)** 组合 `⊕` 在组合前置成立时保持全部不变量，迁移态射 `φ` 保持能力覆盖与语义不变量，前置/态射在运行时以概率 ≥1−α_compose 被复核。则沿路径、交互序列、步态相位、驱动预算、任务组合与能力边界，
`P(∀t≤T: z(t)∈Z_safe) ≥ 1 − Σ_i α_i − Σ_i ε_hand,i − α_lease − α_intent − α_user − α_viable − α_cap − α_act − α_del − α_plan − α_replan − α_data − α_gen − α_compose − Σ_ℓ δ_{ℓ→d}`；
且**数据误差、学生误差、`A_est/A_lb` 之差、LFF 假阴性仍不进入安全上界**：它们只提高拒绝/回退/降级率（可用性），因为放行要求 `G_exact` 在 `A_lb`、`D_cert` 模型、组合见证与能力边界内全部精确通过。承重点从 v15 的 (A11)∧(A13)∧(A14)∧(A15) 扩为再加 (A16)∧(A17)∧(A18)：**"证书便宜精确、包络可信、力矩交付、退路及时"之外，还必须"数据可信、边界不漏、组合不裂"**。这仍是条件保证：数据审计、能力边界监控、组合代数与迁移态射是新的信任锚，由 PFV/LFF/DCL/CCA 的持续证伪、独立数据审计与真机开放世界演练负责，不在定理覆盖范围内。

回退策略：E145 迁移不变量失败 → 拒绝迁移并重认证目标本体，绝不靠调参硬迁；E146 边界漏检 → 收缩 `K_cert`、提高 `ν_max` 保守度、加密监控与人工接管，禁止部署；E147 质量越界 → 冻结 `h(Q)`、独立重审该分层、重标定守卫模型，禁止入证；E148 认证泄漏 → 隔离整条数据血缘、作废相关模型版本、重采独立认证集；E149 组合前置被绕过 → 收紧 `⊕` 前置、运行时强制见证复核、禁拆分认证；E150 覆盖下降或 MRC 超标 → 缩小开放任务范围、降级为监督/原语模式，绝不绕过数据防火墙与精确守卫。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| `Q_lb` 由被审模型/同源数据自评，审计失效 | 高 | 独立审计方 + 分层保守下界 + 血缘隔离 + `h(Q)` 钉版本 + 对抗复核 |
| 训练/认证数据泄漏，假通过 | 高 | DLAT 防火墙 + 血缘重叠检测 + 独立认证集 + 交叉复现 |
| 能力边界漏检 OOD（"不知道的自己不知道"） | 高 | 新颖度监控 + 覆盖密度门槛 + 认证拒绝路径 + 持续漂移/故障证伪 |
| 组合拆分绕过（长任务拆成短任务） | 高 | 组合代数 + 资源可加校验 + 运行时组合见证 + CCA 拆分红队 |
| 跨本体迁移态射错误/不变量破坏 | 高 | 迁移是认证动作 + 形式化不变量保持 + 目标本体 `A_lb` 覆盖校验 |
| 数据投毒/标签噪声/校准过期 | 高 | 数据层 PFV + 来源签名 + 时效下界 + 对抗训练 + 入证门 |
| 通用性度量被平均掩盖 | 中 | `Gen(τ)` 分项报告 + 按任务族分层 + 低覆盖强制降级 |
| `Q_lb` 过保守致可用性骤降 | 中 | `Q_est/Q_lb` 二分 + ACQ 主动补证 + 收紧质量而非放松守卫 |
| 组合/边界状态爆炸 | 中 | 有界证书代数 + 离线预计算 + 提议-处置分担 + 局部复核 |
| 数据/包络/契约版本错配的旧模型服役 | 中 | `h(A),h(Q),h(D),h(κ_c)` 联合钉住 + fail-closed + 再认证门 |

## 6. 本轮最大风险

**一句话**：v16 把 soundness 下沉到数据层后，最大的风险是**用"看起来干净"的数据自我认证**——若 `Q_lb` 由被审模型自评、`D_learn` 与 `D_cert` 血缘未真正隔离、能力边界漏检一次 OOD、或组合前置被"拆任务"绕过，那么"通用机器人安全运行"就会伪装成"到处跑通、处处未认证"；因此质量下界必须独立审计并逐层取保守下界，学习/认证数据必须血缘隔离且检测泄漏，能力边界与组合前置必须持续证伪并在运行时宁拒勿放。
