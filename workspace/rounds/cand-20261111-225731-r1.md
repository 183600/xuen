# 第 55 轮（承接第 54 轮 v16 GroundEdge-GenSim+++；新灵感循环第 1 轮；本轮灵感：「用户需求分析」×「模型预测控制」）

> 前 54 轮从"能力—动作—鲁棒性"一路做到"动作-鲁棒性双证书 + 云边协同"，但始终隐含一个前提：**任务需求是给定的、确定的、一次性的**——任务动作序列 `A_T`、约束与目标都由上游写死。本轮把这个前提本身变成研究对象：用户需求是**潜在的、不完备的、会漂移的**，机器人必须在执行中**边估计、边澄清、边规划**。核心矛盾：H22：需求是潜变量，而 MPC 需要确定的代价与约束；H23：澄清（问）与执行（做）竞争同一动作与时间预算；H24：需求不可行时，"失败"恰恰是最有价值的信息，但如何把不可行转成对用户**最少打扰**的提问仍无定论。

## 0. 直觉与动机

**灵感 1（需求不是约束，而是带不确定性的代价泛函）**
直觉：用户说"把桌子收拾干净"，并没有给出 `C_h`。真实需求更像三元组 `R=(C_h, J_θ, z)`：硬约束（别碰热水）、软偏好（按颜色而非按大小分类）、潜在意图（其实是给客人腾地方）。机器人只能持有后验 `b_t(θ,z)`，并在其后验上做滚动时域决策。这把第 54 轮"任务动作序列已知"的假设替换为"需求后验驱动"。**需求分析的第一性产物不是一个目标，而是一个分布。**

**灵感 2（把信念塞进 MPC 的状态：需求感知滚动时域）**
直觉：标准 MPC 的状态是物理状态 `x_t`；这里扩成 `(x_t, b_t)`。每一步在有限时域 H 上**同时优化物理动作与澄清动作（提问/试探）**：
`min E_{R~b_t}[J_traj] + λ·CVaR_α[违反 C_h] + μ·cost(query) − ν·IG(query)`。
只执行第一步，观测用户反馈，更新 `b_t`，再滚动。需求估计因此不是离线问卷，而是被规划器"按需"驱动——**问什么、何时问，由它对未来动作的影响决定。**

**灵感 3（决策边界 → 只在"问了会改变行动"时才问）**
直觉：用户最烦"什么都问"。关键观察：**并非所有不确定都值得消除**。只有当两个候选需求导致**不同的最优动作**时，歧义才有决策价值。定义决策风险 `DR(b_t)=max_{R,R'∈supp(b_t)} d(π*_R, π*_R')`；仅当 `DR>δ`、信息价值 `VoI>c_query`、且当前动作**不可逆**时触发"即时澄清"（Just-in-Time Clarification）。这把主动学习从"信息最大化"修正为"**决策价值最大化**"，也给了"少问"一个可判定的理由。

**灵感 4（不可行即信息：最小冲突集驱动的需求修复）**
直觉：当 MPC 对 `b_t` 支撑内的所有需求都不可行时，不要报"做不到"，而是提取**最小不可满足需求子集 MURS**（去掉任一元素就可行的最小冲突集），把它变成一句人能回答的问题："进厨房和保持安静只能二选一，你要哪个？"这把第 53 轮的 Explain（解释为什么失败）从"鲁棒性空间"推广到"**需求空间**"，形成 **需求→规划→不可行证书→最小冲突提问→需求修复** 的双向协商闭环。

**灵感 5（需求漂移与滚动契约）**
直觉：用户需求会变（累了、来客人了、目标改了）。用反馈残差的 CUSUM/变点检测识别漂移；一旦漂移，信念变宽、承诺收缩（缩短有效视界、加大安全裕度、提高试探频率）。于是机器人不是"一次对齐、终身使用"，而是**每个滚动窗口重新签订一份会过期的需求契约**；旧窗口的保证在漂移后自动失效，避免"用昨天的偏好做今天的决策"。

**灵感 6（需求层叠加到金字塔）**
直觉：在第 54 轮动作-鲁棒性金字塔 `𝕃/𝔸` 之上加 **需求层 ℚ**：`ℚ0` 物理/安全可行性，`ℚ1` 显式硬约束，`ℚ2` 隐式偏好，`ℚ3` 潜在意图。跨层证书必须同时携带"需求满足证书 + 动作证书 + 鲁棒性谱"，否则任一层成功都可能掩盖另一层的**需求误读**。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（用户需求模型）**
用户需求 `R = (C_h, J_θ, z, τ_R)`：硬约束 `C_h`、由 `θ` 参数化的软代价 `J_θ: Ξ→ℝ`（轨迹空间上的偏好）、潜在意图 `z`、漂移时间尺度 `τ_R`。机器人维护后验 `b_t(θ,z) = P(θ,z | F_{0:t})`，`F_{0:t}` 为纠正、排序、接受/拒绝、演示等异构反馈。需求分布支撑 `Ω_R(t) = supp b_t`。

**定义 122（需求满足度）**
策略 `π` 对真实需求 `R` 的满足度
`sat(π; R) = P_{ξ~π}[ J_θ(ξ) ≤ ε_u ∧ ξ ⊨ C_h ]`。
称 `π` 为 `(1-β_u)`-满足，若 `sat(π;R) ≥ 1-β_u`。注意这是**概率**满足，允许偏好代价与硬约束同时参与。

**定义 123（需求感知 MPC / RMPC）**
在扩展状态 `(x_t,b_t)` 与视界 `H` 上求解联合动作-澄清序列
```
π* = argmin_{a_{0:H}, q_{0:H}}  E_{R~b_t}[ Σ_k J_θ(x_k,a_k) ] + λ·CVaR_α[1(ξ ⊭ C_h)]
        + μ·Σ_k cost(q_k) − ν·Σ_k IG(q_k; b_t)
s.t.  x_{k+1}=f(x_k,a_k),  g(x_k,a_k) ≤ 0,
      x_H ∈ X_cert(b_H),  q_k ∈ Q_feasible(x_k)
```
仅执行 `(a_0,q_0)`，观测反馈后更新 `b_t` 并重规划。`X_cert(b_H)` 为**决策稳定终集**：进入后剩余需求歧义不再改变最优首动作。

**定义 124（决策风险与即时澄清触发）**
两需求 `R,R'` 在状态 `x` 下**决策等价**当且仅当 `π*_R(x)=π*_R'(x)`。决策风险 `DR(b_t)=max_{R,R'∈Ω_R(t)} d(π*_R, π*_R')`。触发澄清条件：
```
DR(b_t) > δ_dec  ∧  VoI(q*) = E[ΔJ | q*] − c_query > 0  ∧  a_0 不可逆
```
其中 `VoI` 为期望代价下降扣除提问成本；不可逆动作指 `¬∃a' : f(x,a')=x`（如打碎、越界、公开承诺）。

**定义 125（最小冲突需求集 MURS）**
对需求约束集 `C = C_h ∪ {软偏好离散化元素}`，称 `M ⊆ C` 为最小不可满足子集，若 `M` 不可行且 `∀ M'⊊M` 可行。冲突提问 `Q(M)` 要求用户在 `M` 中选择放弃/放松一项，或给出优先级。MURS 是**解释"为什么做不到"的最短原因**，也是需求修复的最小编辑目标。

**定义 126（滚动需求契约与漂移）**
滚动契约 `C_H(t) = (b_t, H, δ_safe(t), exp = t+H)`，仅在有效期内被下游证书采信。漂移分数 `D_t = max_k |r_k − r̂_k|/σ_r`（`r` 为反馈残差，`r̂` 为预测），CUSUM 统计量 `S_t = max(0, S_{t-1}+D_t−k)`；`S_t>h` 触发信念重置与承诺收缩 `δ_safe ↑, H ↓`。

## 2. 关键算法 伪代码

### IP-121 RU（Requirement Update）

```python
def requirement_update(belief, feedback):
    # 异构反馈统一成对 (θ,z) 的似然
    if feedback.type == 'correction':
        likelihood = correction_likelihood(feedback.traj, belief)
    elif feedback.type == 'ranking':
        likelihood = bradley_terry(feedback.pairs, belief)
    elif feedback.type == 'accept_reject':
        likelihood = bernoulli_sigmoid(feedback.y, belief)
    elif feedback.type == 'demonstration':
        likelihood = max_ent_irl(feedback.traj, belief)
    return normalize(belief * likelihood)
```

### IP-122 RMPC（Requirement-aware MPC）

```python
def rmpc(x0, belief, H, theta_cfg):
    # scenario / shooting MPC：同时采样需求与动作-查询序列
    best = None
    for R in sample(belief, n=theta_cfg.n_scenarios):
        for seq in shooting(candidates(x0, H)):
            J = task_cost(seq, R) \
              + theta_cfg.lam * cvar_violation(seq, R, alpha=theta_cfg.alpha) \
              + theta_cfg.mu * query_cost(seq) \
              - theta_cfg.nu * info_gain(seq, belief)
            if feasible(seq) and terminal_in(seq[-1], X_cert(belief)) and better(J, best):
                best = (seq, J)
    return best.seq[0] if best else ('infeasible', murs_probe(belief))
```

### IP-123 JITC（Just-in-Time Clarification）

```python
def just_in_time_clarify(belief, x, a0, delta_dec, c_query):
    pi_star = {R: argmin_action(R, x) for R in belief.support()}
    DR = max_distance(pi_star.values())
    a0_irreversible = not exists_inverse(x, a0)
    if DR > delta_dec and a0_irreversible:
        q = argmax_q(voi(q, belief, x) - c_query)
        if voi(q, belief, x) > c_query:
            return q                     # 先问再做
    return None                          # 直接执行
```

### IP-124 MCR（Minimal Conflict Repair）

```python
def extract_murs(constraints, feasible_fn):
    # QuickXplain / 删除过滤：得到最小不可满足子集
    if feasible_fn(constraints):
        return None
    M = deletion_filter(constraints, feasible_fn)
    return M

def conflict_query(M, belief):
    # 把 MURS 变成用户可回答的最小问题
    opts = [drop_or_relax(m) for m in M]
    return Question("为继续执行，请选择放松哪一项:", opts, murs=M)

def repair(belief, answer):
    if answer.type == 'drop':
        return restrict(belief, lambda R: answer.item not in R.C_h)
    if answer.type == 'priority':
        return reweight(belief, answer.order)
```

### IP-125 RCD（Requirement Change Detection）

```python
def drift_monitor(belief, feedback, S, k, h):
    r = feedback_prediction_residual(belief, feedback)
    D = abs(r) / feedback.noise_sigma
    S = max(0.0, S + D - k)
    if S > h:
        return ('drift', reset_belief(prior), shrink_contract(H_factor=0.5,
                                                             delta_safe_factor=1.5))
    return ('stable', S)
```

### IP-126 RCC（需求-鲁棒性联合证书）

```python
def composite_certificate(plan, belief, rho, ConflictFree, delta_safe):
    sat_hat = estimate_sat(plan, belief)
    if sat_hat < 1 - beta_u:
        return ('reject', 'requirement_risk', sat_hat)
    if not ConflictFree:
        return ('reject', 'unresolved_murs')
    if min(rho.values()) < rho_min:
        return ('reject', 'robustness_fail', rho)
    return ('ok', CertReq(sat=sat_hat, rho=rho, drift_bound=delta_safe,
                          expiry=plan.t + plan.H, murs_vacuous=True))
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| RU | O(|F|·|Ω_R|) | O(|Ω_R|) | 似然校准、反馈无偏 |
| RMPC | O(N_s·N_seq·H·|Ω_R|) | O(H·N_seq) | scenario 覆盖真实需求、终集不变 |
| JITC | O(|Ω_R|·|A| + |Q|·VoI) | O(|Ω_R|) | DR 上界、动作可逆性判定 sound |
| MCR | O(|C|·T_feas) | O(|C|) | feasible_fn 单调、MURS 最小性 |
| RCD | O(1) 每步 | O(1) | 残差零均值、CUSUM 阈值标定 |
| RCC | O(|Ω_R|·H + |𝔇_ρ|) | O(H+|𝔇_ρ|) | 联合证书 sound、契约未过期 |

**正确性定理（Requirement-Aware Receding-Horizon Soundness）**
假设第 54 轮 (A26)-(A28) 成立；**(A29)** 真实需求 `R*∈Ω_R(0)` 且反馈似然校准（`b_t` 为 `R*` 的 `ε_b`-近似后验）；**(A30)** 决策稳定终集 `X_cert` 在 `(x,b)` 上不变，且进入后首动作对 `Ω_R` 保持不变；**(A31)** 用户对冲突问题如实回答（或有界噪声 `ε_q`）。则累计需求后悔满足
```
Regret_T ≤ O(√(T·H·log|Ω_R|)) + T·ε_b + N_query·ε_q + T·P(drift undetected)
```
且 `P(部署轨迹 ⊨ C_h 且 J_θ ≤ ε_u) ≥ 1 − β_u − P(δ_safe 超界) − P(冲突修复耗尽)`。关键：**后验校准**、**决策稳定终集**、**冲突最小性**三者共同把"猜用户"变成可审计的滚动证书。

## 4. 实验设计 E162–E166

| 实验 | 指标 | 目标 |
|---|---|---|
| E162 需求估计精度 | 相对 oracle 的 regret、参数后验 NLL | regret ≤ 0.1·oracle 基线，NLL 校准误差 ≤ 0.05 |
| E163 即时澄清 vs 常问/不问 | 任务成功率、每回合提问数、打扰代理分、后悔 | 提问数降 ≥ 40%，成功率不降，后悔降 ≥ 15% |
| E164 最小冲突修复 | 从不可行到可行的提问次数、MURS 命中率 | ≤ 2 次提问恢复可行，MURS 精确率 ≥ 90% |
| E165 需求漂移适应 | 变点后恢复时延、误报率 | 恢复 P95 ≤ 3 回合，误报 ≤ 5% |
| E166 UniBot 端到端 | 布置餐桌/收纳/陪护任务成功率、干预次数 | 成功率 ≥ 85%，用户干预次数降 ≥ 30% |

**基线**：静态规格 MPC（把首次需求写死）、先问后做（问卷式全量澄清）、纯 RL/IL 策略、无 CVaR 的期望 MPC。**消融**：去掉 JITC、去掉 MCR、去掉 RCD，验证三者各自贡献。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 需求假设类错设（真实偏好不在 `Ω_R`） | 高 | 开放世界先验 + 后验校准检验 + 兜底"安全中性策略" |
| 澄清过度导致用户疲劳 | 高 | JITC 决策风险门槛 + 提问预算 + 用户打断即静默 |
| 连续约束下 MURS 不唯一/爆炸 | 中 | 离散化 + QuickXplain 剪枝 + 冲突聚类 |
| 阿谀式偏好迎合（optimizing inferred ≠ welfare） | 高 | 保留不可协商硬约束 + 价值对齐红队 + 第三方审计 |
| 漂移误报导致策略震荡 | 中 | CUSUM 滞回 + 最小驻留时间 + 回滚锚点 |
| 需求后验与鲁棒性证书耦合失效 | 中 | 契约过期即失效 + 双证书联合拒收 |

## 6. 本轮最大风险

**一句话**：把需求当作带漂移的潜变量、用滚动时域 MPC 去"边猜边问边做"，让系统首次能够对"用户到底想要什么"给出可审计的概率保证，但其 soundness **同时押注在后验校准、用户如实回答、以及决策稳定终集的不变性**上；一旦真实偏好落在假设类之外，JITC 会自信地不问、MCR 会基于错误冲突提问、RCD 会把噪声当漂移，机器人将以"高置信度的需求误读"高效地做错事，故必须用 **开放世界后验校准 + 不可协商硬约束 + 提问预算与人工打断** 三重护栏，宁可多问一句"这是你要的吗"，也绝不把后验的自信当作需求的真相。

# 第 55 轮产物 · 创新点清单 v32：GroundEdge-ReqMPC（RU×RMPC×JITC×MCR×RCD×RCC）

> 承接第 54 轮产物 v31。本轮把"任务需求已知"这一隐含前提显式化为**带漂移的需求后验**，并给出需求感知的滚动时域决策栈：
> - **RU（Requirement Update）**：从异构用户反馈在线更新需求后验 `b_t(θ,z)`；
> - **RMPC（Requirement-aware MPC）**：在扩展状态 `(x,b)` 上联合优化"做"与"问"；
> - **JITC（Just-in-Time Clarification）**：以决策风险 `DR` 与信息价值 `VoI` 判定何时澄清；
> - **MCR（Minimal Conflict Repair）**：从不可行中提取 MURS，转成最小冲突提问并修复需求；
> - **RCD（Requirement Change Detection）**：CUSUM 检测需求漂移并收缩契约；
> - **RCC（Requirement-Robustness Composite Certificate）**：需求满足 + 动作 + 鲁棒性的联合证书。
>
> IP 编号：IP-121~IP-126（共 6 个新增），升级 IP-115/117/118 以纳入需求后验与契约过期语义。

```python
        L = max_ent_irl(feedback.traj, belief)
    else:
        L = 1.0
    post = normalize(belief * L)
    return calibrate(post, feedback.calibration_set)
```

### IP-122 RMPC

```python
def rmpc(x0, belief, H, cfg):
    best = None
    for R in sample(belief, n=cfg.n_scenarios):
        for seq in shooting(candidates(x0, H)):
            J = task_cost(seq, R) \
              + cfg.lam * cvar_violation(seq, R, alpha=cfg.alpha) \
              + cfg.mu * query_cost(seq) \
              - cfg.nu * info_gain(seq, belief)
            ok = feasible(seq) and terminal_in(seq[-1], X_cert(belief))
            if ok and (best is None or J < best.J):
                best = Plan(seq, J, R)
    if best is None:
        return ('infeasible', extract_murs(belief, cfg))
    return ('ok', best.seq[0])
```

### IP-123 JITC

```python
def just_in_time_clarify(belief, x, a0, delta_dec, c_query):
    pi_star = [argmin_action(R, x) for R in belief.support()]
    DR = max_pairwise_distance(pi_star)
    if DR <= delta_dec or has_inverse(x, a0):
        return None
    q = argmax_q(voi(q, belief, x) - c_query)
    return q if voi(q, belief, x) > c_query else None
```

### IP-125 RCD

```python
def drift_monitor(belief, feedback, S, k, h):
    r = feedback_prediction_residual(belief, feedback)
    D = abs(r) / max(feedback.noise_sigma, eps)
    S = max(0.0, S + D - k)
    if S > h:
        return ('drift', reset_belief(belief.prior),
                shrink_contract(H=0.5 * belief.H, delta_safe=1.5 * belief.delta_safe))
    return ('stable', S)
```

```python
def composite_certificate(plan, belief, rho, conflict_free, beta_u):
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| RU | O(\|F\|·\|Ω_R\|) | O(\|Ω_R\|) | 似然校准、后验一致性 |
| RMPC | O(N_s·N_seq·H·\|Ω_R\|) | O(H·N_seq) | scenario 覆盖真实需求、终集不变 |
| JITC | O(\|Ω_R\|·\|A\|+\|Q\|·VoI) | O(\|Ω_R\|) | DR 上界 sound、可逆性判定 sound |
| MCR | O(\|C\|·T_feas) | O(\|C\|) | feasible_fn 单调、MURS 最小性 |
| RCD | O(1)/步 | O(1) | 残差零均值、阈值标定 |
| RCC | O(\|Ω_R\|·H+\|𝔇_ρ\|) | O(H+\|𝔇_ρ\|) | 联合证书 sound、契约未过期 |

**正确性定理（Requirement-Aware Receding-Horizon Soundness）**
假设第 54 轮 (A26)-(A28) 成立；**(A29)** 真实需求 `R*∈Ω_R(0)` 且后验 `ε_b`-校准；**(A30)** 决策稳定终集 `X_cert` 在 `(x,b)` 上不变；**(A31)** 冲突回答有界噪声 `ε_q`。则
```
Regret_T ≤ O(√(T·H·log|Ω_R|)) + T·ε_b + N_query·ε_q + T·P(drift undetected)
P(deploy ⊨ C_h ∧ J_θ ≤ ε_u) ≥ 1 − β_u − P(δ_safe 超界) − P(冲突修复耗尽)
```
三个充分条件缺一不可：**后验校准**（否则问错）、**决策稳定终集**（否则滚动不收敛）、**MURS 最小性**（否则修复提问冗余或歧义）。

## 6. 本轮最大风险

**一句话**：把需求当作带漂移的潜变量、用滚动时域 MPC 去"边猜边问边做"，让系统首次能对"用户到底想要什么"给出可审计的概率保证，但其 soundness **同时押注在后验校准、用户如实回答、以及决策稳定终集的不变性**上；一旦真实偏好落在假设类之外，JITC 会自信地不问、MCR 会基于错误冲突提问、RCD 会把噪声当漂移，机器人将以"高置信度的需求误读"高效地做错事，故必须用 **开放世界后验校准 + 不可协商硬约束 + 提问预算与人工打断** 三重护栏，宁可多问一句"这是你要的吗"，也绝不把后验的自信当作需求的真相。
