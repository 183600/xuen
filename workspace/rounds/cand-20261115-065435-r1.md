# 第 70 轮（承接第 69 轮「FLUID-RAS 交互消歧闭环」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「服务设计」×「自主导航」）

> R69 让系统学会「看 / 问 / 触」以消解动作层面的 epistemic 歧义，但它仍然把导航当成**一次任务求解**：一个委托人、一条轨迹、一个标量风险。真实导航却是一段**服务关系**——有人被接、被等、被载、被交接；沿途有多个触点、多个利益相关者、多个「关键时刻」；用户记住的不是你的规划器，而是你有没有兑现承诺、出错时有没有好好补救。R69 的「问」只回答了「我该向谁求证」，却没有回答「**我对谁承诺了什么、承诺兑现不了怎么办、该让谁知道**」。
>
> 本轮两个灵感恰好补上这个缺失：
> - **服务设计**把导航从「轨迹优化」重述为「承诺—证据—交付—补救—审计」的服务闭环：服务蓝图区分前台与后台，关键时刻决定信任，服务补救把失败变成第二次赢得信任的机会，价值由服务提供者与受益者共同生产；
> - **自主导航**给出这个闭环的物理底座：定位、避障、社交空间、多人流、长时程与交接，都是承诺必须落到实处的约束。
>
> 核心命题：**把「不确定性」从只可「减小」（R69）或「收紧」（R68）的对象，升级为还可以「缔约、披露、对冲、补救」的对象；导航控制器维护的不是单一风险标量，而是一张服务契约的松弛资产负债表；只有当不确定性威胁到安全承诺时才退化回 R69/R68。** 命名 **COVENANT-RAS**（Contract-aware, Visibility-governed, Escalation-and-recovery Navigation with Auditable Trust）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**我答应了谁什么，兑现不了时我打算怎么办**」。

## 0. 直觉与动机

**灵感 1（服务设计 → 导航是旅程，不是轨迹）**
直觉：用户从不体验「一条路径」，用户体验的是**一段旅程**：被叫到、被靠近、被等待、被载着走、被放下、被交接。服务设计把这段体验拆成若干触点与关键时刻（moment of truth），并追问：在哪一个瞬间，用户对系统的信任被建立或被破坏？自主导航目前的评价指标是到达时间、路径长度、碰撞率、舒适度，全是**单点/单轨迹**的；它没有「我答应过你 4 分钟」「我答应过不跟得太近」「我答应过在门口等你」这种跨触点的承诺对象。于是系统可以「技术上安全」却在服务上持续违约，而自己毫无察觉。

**灵感 2（承诺 → 不确定性的第三种处置方式，也是「契约资产负债表」）**
直觉：R68 的答案是「不确定就收紧」，R69 的答案是「值钱就去问」。但人类处理不确定性还有第三条路：**缔约**。「我 4±1 分钟内到；若超时我会改道并提前告诉你；若仍超时，你可以取消且不收等待费。」这句话既没有消除不确定性，也没有简单减速，而是把残余不确定性**定价、披露并预先分配责任**。把每条未消解的不确定性视为一项**负债**，把每条承诺的容差视为**资本**，控制器要维持的就不是 λ_floor，而是「资本 ≥ 负债」的**契约平衡表**。R68 的保守是「提高资本充足率」，R69 的交互是「尽职调查」，披露是「对冲」，补救是「保险」。四种工具，同一个账本。

**灵感 3（服务蓝图 → 前台/后台是一条可设计的接线，而非 UI 细节）**
直觉：R69 默认「有歧义就问」，但服务设计提醒：不是所有不确定性都该给用户看。看得见的东西（前台）会占用注意力、泄露隐私、暴露可被利用的犹豫；看不见的东西（后台）必须由系统自己扛。服务蓝图用三条线切开这三层：交互线（用户↔前台）、可见性线（前台↔后台）、内部交互线（后台↔支援系统/其他机器人）。于是「可见性」成为一个**控制变量**：只有当用户能据此行动、且收益大于认知负荷与泄露风险时，才把不确定性搬到前台；否则压到后台，并在后台用保守控制兜底。过度披露和隐瞒一样，都是服务失败。

**灵感 4（关键时刻 → 信任只在少数触点上结算）**
直觉：一段 10 分钟的行程里，用户不会逐帧评估你的控制律；他只在召唤响应、上车、急停、让行、到达、交接这几个**关键时刻**形成判断。每个关键时刻有不同的信任权重与不同的承诺集合。这给出一个极重要的工程后果：**承诺与证据应当按关键时刻组织，而不是按控制周期组织**。控制器可以高频运行，但契约的记账与披露必须是事件驱动的、可解释的、可复盘的。

**灵感 5（服务补救 → 违约不是终点，而是信任的第二次机会）**
直觉：服务设计里有一个反直觉结论——**服务补救悖论**：一次被迅速、真诚、有效地补救的失败，可能让用户信任高于从未失败。导航系统目前把违约当作「失败 metric +1」；但用户真正在意的是「你出错后有没有告诉我、有没有补偿、有没有把我安全送到」。于是「重议 ETA、改走更稳但更慢的路、让行并解释、请求接管、提供替代方案」应当成为**一等动作**，进入与任务动作同一个安全认证与审计体系，按「期望信任损失」而不是「任务完成度」来优化。前提是：补救必须**预先承诺**，而不是事后临时编。

**灵感 6（价值共创与多主体 → 服务对象通常不止一个，公平本身就是承诺）**
直觉：服务主导逻辑说，价值永远由提供者与受益者**共同生产**：用户确认目的地、扶住门、让出通道、在需要时接管。导航因此不是「机器人对世界」的单人问题，而是「机器人对一群人」的分配问题。走廊里同时有赶时间的人、行动不便的人、另一台 AMR、以及楼宇管理者；「先服务谁、谁让行、谁的空间被压缩」是一个**公平**问题。R69 的 VoI 是单主体的；这里必须升级为**社会 VoI**：只有当消歧会改变公平前沿时才值得去问或去看；否则问得越多，只是把注意力成本转嫁给被服务者。

**灵感 7（承诺是新的攻击面 → 契约博弈与「合法性幻觉」）**
直觉：一旦系统会「承诺」，就有人会**博弈承诺**：伪造紧急以插队、诱导系统披露犹豫再加以利用、故意触发补救以索取补偿、用多人共谋把责任推给机器人。更隐蔽的是**合法性幻觉**：一份写得很漂亮、审计得很完整的契约，可能只是把残余风险**合法化**并转嫁给最没有议价能力的人（例如让行动不便者承担更多绕行）。因此本轮必须同时交付：承诺校准门（不许过度承诺）、契约博弈干扰集、披露后悔比、以及「补救不得以牺牲第三方安全为代价」的硬约束。

## 1. 形式化定义（增量：定义 310–324）

**定义 310（COVENANT-RAS 总览）** COVENANT-RAS = (SCL, JRN, FVB, CARA, CVoI, SRL, MSF, SPA, RAS-WM‡)。四不变式：
(i) **实时流零学习写操作**（继承 R69 定义 293-i）；
(ii) **承诺完整性**：每条承诺在提交时必须携带校准置信 `conf_i`、容差 `tol_i`、可见性策略 `vis_i` 与补救条款 `remedy_i`；运行期不得静默增强或削弱承诺；
(iii) **补救预承诺**：任何预测违约概率超过其校准上界的承诺，必须在提交前绑定一条预审计补救路径，或当场拒绝/重议；
(iv) **证据与审计**：承诺、披露、补救全部进入不可篡改日志，并回灌下一轮承诺校准。

**定义 311（服务契约账本 SCL）** 契约 `C = {p_i}`，每条承诺 `p_i = (o_i, target_i, tol_i, conf_i, remedy_i, vis_i, owner_i)`：`o_i` 为义务类型（到达时间 / 舒适度 / 个人空间 / 隐私 / 公平 / 可用性 / 交接），`target_i` 为目标值，`tol_i ≥ 0` 为容差，`conf_i ∈ (0,1)` 为**承诺覆盖率**（声称「95% 准点」就必须在 95% 的旅程上兑现），`remedy_i` 为违约时绑定的补救动作，`vis_i` 为可见性策略，`owner_i` 为责任主体（乘客 / 行人 / 运营方 / 楼宇方）。契约操作：`commit, renegotiate, transfer, discharge, breach`。**契约可行** ⇔ 联合机会约束 `P(∧_i v_i(a,o) ≤ tol_i) ≥ 1 − ε`，其中 `v_i` 为承诺 `i` 的预测违约量。硬规则：**任何承诺不得在提交后被静默改写**，只允许显式 `renegotiate` 或 `transfer`。

**定义 312（旅程、触点与服务蓝图 JRN）** 旅程 `J = (s_0, …, s_n)`；每个阶段 `s_k` 有触点集 `T_k` 与关键时刻 `M_k`（召唤响应 / 靠近 / 上车 / 行驶 / 下车 / 交接），关键时刻带信任权重 `ω_k`。服务蓝图 `B = (L_int, L_vis, L_intl)`：交互线 `L_int`（用户↔前台）、可见性线 `L_vis`（前台↔后台）、内部交互线 `L_intl`（后台↔支援系统/其他机器人）。交接算子 `⊗ : C_k → C_{k+1}` 继承未完成义务：**不允许在交接处静默丢弃承诺**（定义 323）。承诺按关键时刻结算，而非按控制周期结算。

**定义 313（前台/后台可见性治理 FVB）** 对每个未消解不确定性 `u`，定义可行动性 `A(u) = E[用户若知情后的后悔减少量]`、认知负荷 `L(u)`、隐私/对抗泄露 `R(u)`。披露决策 `δ(u) ∈ {front, back, on_request}`，由 `δ* = argmax_δ [A(u) − αL(u) − βR(u)]` 给出，并受可见性预算 `Σ L(u) ≤ L_max` 约束。**只有用户能据此行动时才搬到前台**；否则压到后台，并在后台以 R68 保守兜底。可见性线是可设计的策略，不是事后 UI。

**定义 314（契约感知风险分配 CARA）** 对承诺 `i`，归一化松弛 `s_i(a,o) = (tol_i − v_i(a,o)) / σ_i`。CARA 选择动作
`a* = argmin_a E[task_cost(a)]`，s.t. `v_i^{1−ε_i}(a,o) ≤ tol_i, ∀i`，`Σ_i ε_i = ε`，
其中 `v_i^{1−ε_i}` 为校准后的 `1−ε_i` 分位预测。等价地：在所有承诺的**认证松弛**均非负的可行集内优化任务代价；若可行集为空，进入定义 322 的降级链。R68 的 λ_floor 恰是「只有一条容差为 0 的安全承诺」时的特例。

**定义 315（契约相关 VoI，CVoI）** 设契约短缺 `D(o) = Σ_i (tol_i − v_i(a,o))^−`（负部）。信息动作 `g` 的契约价值
`VoI_C(g) = E[D(o)] − E_{y~p(·|g,o)}[D(o,y)]`。
选择 `g* = argmax_g [VoI_C(g) − c(g)]`，s.t. 安全认证与交互预算。**若某歧义不改变任何承诺的松弛，则 `VoI_C = 0`，不问**。当契约只含安全承诺时，`VoI_C` 退化为 R69 的动作模态 VoI——这是严格泛化，而不是并列替换。

**定义 316（服务补救库 SRL）** 预审计补救动作 `ρ ∈ {renegotiate, reroute, yield, compensate, explain, escalate/handoff, abort}`，每个带物理/社交成本 `c(ρ)`、时延 `τ(ρ)`、信任损失减少量 `ΔL(ρ)` 与前置条件。违约时选
`ρ* = argmin_ρ [E[trust_loss(ρ)] + c(ρ)]`，s.t. 补救预算、`ρ` 过 C-RAS-WM 认证、且**补救不得把风险转嫁给第三方**。期望信任损失 `E[trust_loss] = (1−p_succ)L_viol + p_succ L_resid − 𝟙[快速且可信]·b_paradox`，其中 `b_paradox` 刻画服务补救悖论窗口。

**定义 317（多主体公平 MSF）** 利益相关者 `j` 的服务水平 `SL_j(a)` 与松弛 `s_j`。公平分配二选一：最大最小松弛 `max_a min_j s_j`，或 Nash 福利 `max_a Σ_j log(s_j + κ)`；并以无嫉妒（envy-free）作为校验。**社会 VoI**：只有当消歧会推动公平前沿时才值得行动；`VoI_social(g) =` 公平前沿的期望位移。

**定义 318（服务承诺审计 SPA）** 记录四元组 `(promise_at_commit, evidence_at_commit, delivered, disclosure/recovery)`。承诺校准误差 `ECE_promise = Σ_b (n_b/N)|acc_b − conf_b|`；可靠图必须单调。博弈检测特征：申报紧急度 vs 经验证紧急度、披露探测频次、补救触发率相对基线、多人共谋模式。结论回灌 SCL 的 `conf_i` 与补救成本先验。

**定义 319（承诺校准门 PCG）** 若 `ECE_promise > τ_pc`，系统只能**下调**承诺（放宽容差或降低 `conf_i`），或拒绝该服务；**绝不允许过度承诺**。这是 R69 模态校准门 MCG 在服务层的对偶：MCG 管「信念可不可信」，PCG 管「承诺兑不兑得起」。

**定义 320（契约博弈干扰集 AIC-COVENANT）** `ℰ_contract = {`伪造紧急/插队、诱导披露后利用、补救套利、承诺胁迫、多人共谋转嫁责任`}`；并入 `ℰ_COV = ℰ_FLUID × ℰ_contract × ℰ_journey`，其中 `ℰ_journey` 覆盖期望漂移、交接错配、跨阶段承诺冲突。

**定义 321（服务证书 J_COV）** `J_COV = (J_FLUID, contract_hash, promise_calibration_ece, disclosure_regret_ratio, recovery_log_hash, fairness_index, journey_version)`。`Valid ⇔ Valid(J_FLUID) ∧ ECE_promise ≤ τ_pc ∧ 无未补救违约 ∧ 证据纪律满足 ∧ 交接承诺完整`。

**定义 322（违约降级链与单调性）** 预测违约时按序执行：`(1)` 用户可交互则 `renegotiate`；`(2)` 预算内 `recover`；`(3)` 降级为只保留安全承诺的 R69/R68 契约；`(4)` 拒绝/中止并给出解释。要求**单调**：任何一步都不得让安全承诺变弱，也**不得静默违约**。这条链保证「服务层退化」永远收敛到 R69 的安全边界，而不是收敛到「什么都不承诺」。

**定义 323（触点与交接不变式）** 跨触点与交接，契约连续：`C_{k+1} ⊇ C_k ⊗ transfer`，即未完成义务必须被显式继承或显式重议；状态与责任主体在交接处必须可追溯；控制连续性沿用 R69 定理 17（提交/换装不变式）⇒ 无突变。用于消除「责任真空」：不允许在换乘、换机器人、换运营方时把承诺悄悄清零。

**定义 324（承诺—证据—补救闭环）** 每个承诺周期：`promise → evidence → delivery → (recovery) → audit → recalibrate`。这是 R69「交互—审计」闭环在服务层的镜像：交互决定「问什么」，契约决定「答应什么」，审计决定「下次还敢不敢这么答应」。

```python
# IP-264 SCL：服务契约账本（承诺不可静默改写）
class ServiceContractLedger:
    def commit(self, promises, o):                  # 提交前必须绑定 remedy 与 conf
        for p in promises:
            assert p.conf <= self.calibrated_coverage(p)   # PCG：不许过度承诺
            assert p.remedy is not None or p.conf == 0.0
    def balance(self, o): return sum(slack(p, o) for p in self.active)
    def threatened(self, o): return min(slack(p, o) for p in self.active) < 0

# IP-265 JRN：旅程/触点/蓝图（承诺按关键时刻结算）
class JourneyModel:
    def stage(self, t): ...
    def moments_of_truth(self): ...                 # 召唤/靠近/上车/行驶/下车/交接
    def transfer(self, C_k, k):                     # 交接不丢承诺
        return inherit(C_k, self.stage(k + 1).obligations)

# IP-266 FVB：前台/后台可见性治理
def disclose(u, ctx):
    A, L, R = actionability(u, ctx), load(u), leakage(u)
    score = A - alpha * L - beta * R
    return "front" if score > gamma and budget.ok(L) else "back"

# IP-267 CARA：契约感知风险分配（联合机会约束）
def contract_action(modes, C, o):
    feasible = []
    for a in modes:                                 # R69 FMP 给出的多模态候选
        if all(quantile(v_i, a, o, 1 - eps_i) <= tol_i for p in C):
            feasible.append(a)
    return min(feasible, key=task_cost) if feasible else None

# IP-268 CVoI：只问「会改变承诺」的歧义（R69 MINT 的服务层升级）
def choose_contract_interaction(C, o, budget):
    if not C.threatened(o): return None             # 不威胁承诺 → 不问
    return argmax_g([VoI_C(g, C, o) - c(g)
                     for g in info_candidates() if budget.allow(g)
                     and c_ras_wm.certify_info(g, o) and VoI_C(g, C, o) > c(g)])

# IP-269 SRL：服务补救（信任损失最小化，预审计）
def recover(violated, o, trust):
    rho = min(recovery_library(violated),
              key=lambda r: expected_trust_loss(r, o, trust) + cost(r))
    return rho if c_ras_wm.certify(rho, o) and not shifts_risk_to_third_party(rho) else None

# IP-270 MSF：多主体公平分配（最大最小松弛 / Nash）
def fair_allocate(stakeholders, C, o):
    return argmax_a(min(slack_j(a, o) for j in stakeholders))   # 或 Nash 福利

# IP-271 SPA / IP-272 PCG / IP-273 AIC-COVENANT / IP-274 J_COV（审计、校准门、干扰集、证书）
def audit_and_recalibrate(logs, C):
    ece = promise_ece(logs)
    if ece > TAU_PC: C.downgrade()                  # 只许下调承诺
    return J_COV(logs, ece, disclosure_regret(logs), fairness_index(logs))

# IP-275 主闭环（R69 之上加服务层，安全侧不弱化）
def COVENANT_round(M, o):
    # 0) R69：动作层不确定性（原样继承）
    U_ale, U_epi, modes = M.r69.uncertainty(o)
    C = M.scl.active(); J = M.journey.stage(o)
    # 1) 只对「威胁承诺」的歧义发起契约相关交互
    g = M.cvoi.choose(C, o, M.budget)
    if g is not None:
        modes = M.cia.update_belief(modes, M.cia.execute(g))
    # 2) 契约感知动作选择（联合机会约束 + R69 认证前缀）
    a = M.cara.choose(modes, C, o)
    if a is None:                                   # 可行集为空 → 降级链
        rho = M.recovery.recover(C.violated(o), o, M.trust)
        if rho is None: return M.scl.renegotiate_or_refuse(C, o)
        a = M.recovery.apply(rho, modes)
    # 3) 可见性：只披露用户能行动的残余不确定性
    for u in M.r69.open_uncertainties():
        M.scl.disclose(u, M.fvb.decide(u, o))       # front / back / on_request
    # 4) 执行（R69 认证前缀），关键时刻结算承诺
    k = M.c_ras_wm.certified_prefix(M.ach.propose(a, M.vista.H), ..., wm_preds)
    if M.journey.at_moment_of_truth(o):
        M.scl.settle(M.journey.current(), o)        # 记录 delivered / breach
    # 5) 审计 + 重新校准承诺；输出服务证书
    return k, M.audit_and_recalibrate(M.scl.logs(o), C)
```

## 3. 推导

**引理 19（契约松弛对 R68/R69 的严格包含）** 若契约只含一条容差为 0 的安全承诺，且 `vis = back`、无补救可用，则 CARA 的可行集恰为 R68/R69 的认证安全集，`VoI_C` 退化为 R69 的模态 VoI，`δ*` 恒为后台。故 COVENANT 在该边界上**逐指令等价于 R69**；加入任何时间/舒适/公平承诺只会**收紧或重新分配**约束，不会放松安全。要点：服务层不是替代安全层，而是给安全层加了一张「承诺约束表」，且始终以安全承诺为硬核。

**引理 20（披露价值的倒 U 形）** 设用户可行动性为 `A`，披露带来的后悔减少为 `φ(A)`（凹、饱和），认知负荷与泄露为 `αL + βR`。则期望净收益 `φ(A) − αL − βR` 在 `A` 中等时最大，在 `A→0`（用户无法行动）与 `A→大且已饱和`（信息过载、重复披露）两端都下降。系：**过度披露与隐瞒同罪**；最优可见性策略是内点，而不是「全透明」或「全黑箱」。这解释了为什么「把 epistemic 不确定性全说出来」在服务上是错的——它把内部噪声转嫁成用户的焦虑。

**引理 21（服务补救的信任损失上界与悖论窗口）** 若补救以成功率 `p_succ` 在 `τ_rec` 内恢复松弛，且证据可信，则期望信任损失
`E[L] ≤ (1−p_succ)L_viol + p_succ·L_resid − p_succ·b_paradox·𝟙[τ_rec ≤ τ_fast]`。
当 `L_resid + b_paradox < L_viol` 时，补救后的期望信任可高于违约前（悖论）。界的关键不是「补救越多越好」，而是 `p_succ` 与 `τ_rec`：**慢而不可信的补救比不补救更伤信任**（因为二次违约叠加了「你说谎」的判断）。

**引理 22（多主体公平分配的存在与无嫉妒性）** 若各主体的服务水平集是凸的、松弛函数凹，则最大最小松弛分配存在且 Pareto 有效；Nash 福利最大化分配在可分离效用下满足无嫉妒。系：社会 VoI 只在能推动公平前沿时为正，因此「为了公平而多问」必须有边界——问本身消耗被服务者的注意力与时间，是一种**逆向再分配**。

**定理 18（COVENANT 的安全不弱化与承诺可校准）** 在 A99–A101（校准分位有效、补救预审计、交接承诺继承）下：(a) 对任意状态，COVENANT 的最坏安全风险 ≤ R69；(b) 实际兑现率与承诺 `conf_i` 的偏差 ≤ `ECE_promise`；(c) 违约路径单调，不存在静默违约；(d) `ECE_promise > τ_pc` 或安全承诺不可行时，退化为 R69/R68 纯保守且服务拒绝，而非带病承诺。

**定理 19（公平契约的可实现性与降级一致性）** 在凸服务水平集下，CARA 的可行解集与 MSF 的公平前沿交集非空当且仅当存在同时满足安全承诺与公平约束的分配；若交集为空，降级链按 `renegotiate → recover → safety-only → refuse` 单调收敛到 R69 的可行域。即：**公平不能以安全为代价，安全也不必以歧视为代价**——两者的冲突必须被显式暴露，而不是被优化器平均掉。

## 6. 本轮最大风险

**一句话**：COVENANT-RAS 把「不确定性」变成「可签署的承诺」，但**承诺的合法性本身无法由系统自证**——如果被服务者的真实偏好、议价能力与补救诉求和契约里写的不一致，或者承诺校准在部署分布上悄悄失效，那么一份审计完备、措辞漂亮的契约反而会把残余风险**合法化并转嫁给最没有议价能力的人**（例如让行动不便者承担更多绕行、让赶时间的人承担更多等待），系统于是从「诚实的不知道」升级为「**有文件背书的错**」——服务设计的最大陷阱不是设计得不好看，而是把政治问题伪装成工程问题。

**次级风险与缓解**：
1. **过度承诺 / 承诺校准漂移** → PCG 校准门 + 只许下调承诺 + E302/E312 分布外复检；
2. **契约博弈与披露套利** → `ℰ_contract` 对抗集 + 披露后悔比 + 多人共谋检测（E307）；
3. **补救转嫁第三方风险** → 补救动作过 C-RAS-WM 认证 + 「不得牺牲第三方安全」硬约束（定义 316、定理 19）；
4. **交接处责任真空** → 交接算子 `⊗` + 承诺继承不变式 + E308；
5. **过度披露造成焦虑/隐私泄露** → FVB 倒 U 形门控 + 可见性预算 + E303；
6. **公平与安全的冲突被平均数掩盖** → 交集为空时显式降级并暴露冲突，而不是软约束加权（定理 19）。

**定义 318–319（SPA 审计与 PCG 门控）** 审计 `(commit, evidence, delivered, disclosure/recovery)` 与博弈特征（申报/验证紧急度、披露探测、补救触发率、共谋）；`ECE_promise > τ_pc` 时只许下调承诺或拒绝服务。

```python
# IP-264 SCL：承诺不可静默改写；提交前必须可兑现
class ServiceContractLedger:
    def commit(self, promises, o):
        for p in promises:
            assert p.conf <= self.calibrated_coverage(p)     # PCG
            assert p.remedy is not None or p.conf == 0.0
    def balance(self, o):   return sum(slack(p, o) for p in self.active)
    def threatened(self, o):return min(slack(p, o) for p in self.active) < 0

# IP-265 JRN：旅程/关键时刻/交接不丢承诺
class JourneyModel:
    def moments_of_truth(self): ...                          # 召唤/靠近/上车/行驶/下车/交接
    def transfer(self, C_k, k): return inherit(C_k, self.stage(k + 1))

# IP-266 FVB：可见性治理（倒 U 形，过度披露与隐瞒同罪）
def disclose(u, ctx):
    return "front" if actionability(u, ctx) - alpha*load(u) - beta*leakage(u) > gamma \
                    and budget.ok(load(u)) else "back"

# IP-267 CARA：联合机会约束下的动作选择
def contract_action(modes, C, o):
    ok = [a for a in modes
          if all(quantile(v_i, a, o, 1 - eps_i) <= tol_i for p in C)]
    return min(ok, key=task_cost) if ok else None            # None → 降级链

# IP-268 CVoI：只问会改变承诺的歧义（R69 MINT 升级）
def choose_contract_interaction(C, o, budget):
    if not C.threatened(o): return None
    cand = [g for g in info_candidates() if budget.allow(g) and c_ras_wm.certify_info(g, o)]
    return argmax_g([VoI_C(g, C, o) - c(g) for g in cand]) if cand else None

# IP-269 SRL：预审计补救，按信任损失而非任务完成度优化
def recover(violated, o, trust):
    rho = min(recovery_library(violated),
              key=lambda r: expected_trust_loss(r, o, trust) + cost(r))
    return rho if c_ras_wm.certify(rho, o) and not shifts_risk_to_third_party(rho) else None

# IP-270 MSF：公平分配（最大最小松弛，或 Nash 福利）
def fair_allocate(stakeholders, C, o):
    return argmax_a(min(slack_j(a, o) for j in stakeholders))

# IP-275 主闭环：R69 之上加服务层，安全侧不弱化
def COVENANT_round(M, o):
    U_ale, U_epi, modes = M.r69.uncertainty(o)               # 继承 R69
    C = M.scl.active(); M.journey.stage(o)
    g = M.cvoi.choose(C, o, M.budget)                        # 契约相关交互
    if g is not None:
        modes = M.cia.update_belief(modes, M.cia.execute(g))
    a = M.cara.choose(modes, C, o)                           # 联合机会约束
    if a is None:                                            # 空可行集 → 降级
        rho = M.recovery.recover(C.violated(o), o, M.trust)
        if rho is None: return M.scl.renegotiate_or_refuse(C, o)
        a = M.recovery.apply(rho, modes)
    for u in M.r69.open_uncertainties():
        M.scl.disclose(u, M.fvb.decide(u, o))                # front/back/on_request
    k = M.c_ras_wm.certified_prefix(M.ach.propose(a, M.vista.H), ..., wm_preds)
    if M.journey.at_moment_of_truth(o):
        M.scl.settle(M.journey.current(), o)                 # 结算承诺
    return k, M.audit_and_recalibrate(M.scl.logs(o), C)      # 审计 + 重校准 + J_COV
```

## 4. 推导

**引理 19（契约松弛对 R68/R69 的严格包含）** 安全-only 契约（容差 0、`vis=back`、无补救）下，CARA 可行集 = R68/R69 认证安全集，`VoI_C` 退化为 R69 模态 VoI，`δ*≡back` ⇒ **逐指令等价于 R69**。加入时间/舒适/公平承诺只收紧或重新分配约束，不放松安全。服务层不是替代安全层，而是给安全层加一张以安全为硬核的「承诺约束表」。

**引理 20（披露价值的倒 U 形）** 设披露后悔减少 `φ(A)` 凹且饱和，负荷/泄露为 `αL+βR`，则 `φ(A)−αL−βR` 在中等可行动性处最大，`A→0`（用户无法行动）与 `A→饱和`（信息过载/重复披露）两端都下降。系：**过度披露与隐瞒同罪**；最优可见性为内点，把 epistemic 噪声全说出来等于把内部成本转嫁为用户的焦虑。

**引理 21（补救的信任损失上界与悖论窗口）** `E[L] ≤ (1−p_succ)L_viol + p_succ L_resid − p_succ b_paradox 𝟙[τ_rec ≤ τ_fast]`。当 `L_resid + b_paradox < L_viol` 时补救后信任可高于违约前（服务补救悖论）；关键变量是 `p_succ` 与 `τ_rec`——**慢而不可信的补救比不补救更伤信任**。

**引理 22（公平分配与无嫉妒）** 凸服务水平集 + 凹松弛下，最大最小松弛分配存在且 Pareto 有效；可分离效用下 Nash 福利最大化满足无嫉妒。系：社会 VoI 只在推动公平前沿时为正，「为公平而多问」有边界——问本身是对被服务者注意力/时间的逆向再分配。

**定理 18（安全不弱化与承诺可校准）** A99–A101（校准分位有效、补救预审计、交接承诺继承）下：(a) 任意状态最坏安全风险 ≤ R69；(b) 兑现率与 `conf_i` 偏差 ≤ `ECE_promise`；(c) 违约路径单调、无静默违约；(d) `ECE_promise > τ_pc` 或安全承诺不可行时退化为 R69/R68 纯保守并拒绝服务，而非带病承诺。

**定理 19（公平契约的可实现性与降级一致性）** 凸服务水平集下，CARA 可行集与 MSF 公平前沿交集非空 ⇔ 存在同时满足安全与公平的分配；交集为空时降级链 `renegotiate → recover → safety-only → refuse` 单调收敛到 R69 可行域。**公平不能以安全为代价，安全也不必以歧视为代价**——冲突必须被显式暴露，而不是被加权平均掉。

## 7. 本轮最大风险

**一句话**：COVENANT-RAS 把不确定性变成「可签署的承诺」，但**承诺的合法性无法由系统自证**——若被服务者的真实偏好、议价能力与补救诉求和契约里写的不一致，或承诺校准在部署分布上悄悄失效，那么一份审计完备、措辞漂亮的契约反而会把残余风险**合法化并转嫁给最没有议价能力的人**（行动不便者多绕行、赶时间者多等待），系统从「诚实的不知道」升级为「**有文件背书的错**」——服务设计最大的陷阱不是设计得不好看，而是把政治问题伪装成工程问题。

**次级风险与缓解**：过度承诺/校准漂移（PCG + 只许下调 + E302/E312）；契约博弈与披露套利（`ℰ_contract` 对抗集 + 披露后悔比 + E307）；补救转嫁第三方（C-RAS-WM 认证 + 不得牺牲第三方安全，定理 19）；交接责任真空（`⊗` 继承不变式 + E308）；过度披露致焦虑/隐私泄露（FVB 倒 U 形 + 可见性预算 + E303）；公平与安全冲突被平均掉（交集为空即显式降级，定理 19）。
