# 第 41 轮 · 双灵感落地 v18：协作结构优化（CSO）——多机即多租户、多臂即多角色（「协作结构」横切层 Γ-Plane，四层架构 v6）

> 承接第 40 轮（v17：热预算治理 × 步数感知规划 × 学习-TO 混合轨迹，四层架构 v5）。本轮灵感词「多机协作 / 结构优化」。第一反应是给 v17 再加一层「多机编排」和一层「轻量化 NAS」；但把官方 README 的 N 端口条款、公开榜单快照、以及 12 个 G1_Dex1 任务的 9,600 帧双臂审计并排读完以后，我发现这两个词戳中的不是「再加两个模块」，而是 v17 从未质疑的一个默认：**协作结构本身是给定的**。v17 假设「一个后端服务 N 个独立端口」「两条 7-DoF 臂各自输出绝对目标」「规划器输出一个技能序列」；它只优化资源账本，不优化「谁和谁共享什么、谁和谁以什么角色配合」。于是 v18 的主轴是：**把协作结构（coordination structure）升格为一等优化变量——不是让机器人物理上互相帮忙（官方没有这个场景），而是在两个真实尺度上选择「共享/隔离」的图拓扑：跨端口的共享推理与统计（多租户），以及跨双臂的角色与闭链（多角色）。**

## 0. 联网与本地核实（先事实后推理；口径 2026-11-10）

- **F67（官方 README §5–6，本轮逐字核验）**：评测跨 **N 台测试机器人**随机顺序进行；每台机器人一个固定端口，提交须暴露 8765 起连续 N 个端口；两种实现：①每端口独立进程/独立模型（最稳，N 份显存）；②**多端口共享一个推理后端**（省资源）；**不同端口可能同时被调用**，共享后端必须并发、避免互相阻塞与延迟膨胀；**每个端口对应一台独立机器人上的独立 episode，reset 与历史状态必须隔离、绝不共享**；每步 `get_action` 的时延与内容被记录，**时延平滑性 + 返回动作的统计规律性**是可信度依据，可能与成绩一并展示。
- **F68（公开榜单快照 + 统计，exp/unibot_leaderboard_20261102.json / r16_leaderboard_stats.json，抓取 2026-11-02/04）**：8 个通才模型 × 32 任务；榜首 MolmoAct2 成功率 29.7%、step score 39.0；**step score 是 rubric 部分完成度而非动作步数**：模型级 `step ≈ 0.510 + 1.321·success`（R²=0.9814），逐任务 `b` 均值 1.334、R² 均值 0.9925，256 个 (任务,模型) 点中 `step < success` 的违例为 0；**success 与 step 的排名完全一致**（step 不增加排序信息）。注意：官网当前仍显示 Leaderboard「即将发布」，此快照是公开历史产物，公式按**强先验**而非官方定义使用（A39）。
- **F69（G1_Dex1 双臂协同审计，exp/r41_coop_audit_results.json，12 任务 / 9,600 帧，2026-11-10）**：双臂同时运动占 **47.1%**；双夹爪同时闭合仅 **7.0%**；单左/单右闭合 14.95%/22.29%；双开 55.8%；臂速相关均值 0.277（接近独立）；双闭合帧的相对末端距离标准差总均 **31.2 mm**——**PlugInEthernet 1.43 mm（准刚性闭链）**，而 PackDoll 51.9 mm、ZipUp 42.2 mm、Unlock 32.3 mm、FoldTowel 28.1 mm。**结论：真正的闭链共持是少数派；大多数「协同」是共享工作空间的非接触协调或顺序交接。**
- **F70（机队校准机制检查，exp/fleet_results.json S2）**：干净机队中，孤立校准误差 0.1341、分层收缩 0.1155、全机队均值 0.1917（越低越好），分层把 warmup 从 5 个 episode 降到 2；存在一个 rogue 端口时，孤立 0.1341、分层 0.1493、全机队均值 0.3826——**共享在干净机队有益，但会被单个坏端口污染**。合成检查，非榜单证据。
- **F71（机队伸缩机制检查，exp/fleet_results.json S3）**：N=3/8 时最佳静态 chunk T=3，N=12 时 T=5，N=20 时 T=9；静态 T=1/2 在 N≥3 即违反 SLO；自适应 chunk 在各 N 下匹配最佳静态且无 SLO 违例——**共享后端的关键不是「共享」，而是「按 N 与截止期选择共享的粒度」**。
- **F72（文献先例）**：CRISP（arXiv 2611.07268）把双臂闭链作为 holonomic constraint 进 NMPC，在 G1 上做全身协同；Co-VLA（2606.20285）用「共享 latent + 每臂残差 latent」的结构化动作专家，在紧协同任务上 +27pp、OOD 13%→27%；PhysGraph（2603.01436）把双臂系统建成 kinematic graph；Dual-Arm Whole-Body Planning（2511.08778）利用共享躯干关节的结构把 19-DoF 规划压到 0.4s/99.9%；InstAgent（2610.23098）用行为树显式编码异构机器人协作的依赖与交接，20 个真机任务 +15–25pp；Learning from Fleet Experience（2610.25736）在最多 96 台机器人上做集体经验学习；DC-Ada（2604.03905）保持共享策略冻结、只适配每台机器人的观测变换；CTME（2610.17409）把测试时协调的频率/权限作为结构原语。**这些先例共同说明：协作的收益来自「结构化的共享」，而不是「更多的共享」。**

## 1. 研究者直觉（先直觉与动机，后形式化）

**直觉 1（「多机」有三种读法，只有两种是真的）**。第一种是「多台机器人物理协作」——官方 README 明确 N 台是独立机器人、独立 episode、独立端口，**不存在单场景内的多机器人协作**；把它做成任务分配/编队/共享地图是零测试价值的过度设计。第二种是「多租户共享后端」——官方 Approach 2 明确允许，且不同端口可能同时调用，这是真实的多机协作。第三种是「一台 G1 的两条臂」——官方任务含双手协调，F69 证明它有真实的协同含量（47.1% 双臂同时运动），但真正的闭链只占 7%。所以 v18 只做后两种，并把第一种明确登记为「不做」；这不是保守，而是把复杂度预算花在能被官方接口验证的地方。

**直觉 2（结构优化不是「少放材料」，是「材料只放在载荷路径上」）**。机械结构优化的核心不是把零件做小，而是让材料沿着载荷路径分布。把这个隐喻搬到本赛题：**「载荷」是得分与可信度信号，「材料」是共享的计算、统计与记忆**。一条协作边只有在它承载得分/可信度载荷时才值得存在；不承载载荷的共享（跨端口的 episode 状态、无用的多租户舱壁、全局开启的闭链）都是寄生质量。于是「多机协作 × 结构优化」合起来就是：**在「端口 × 臂 × 共享模块」的图上，只保留那些 VoC（价值耦合）为正的边。** 这比 v17 的「资源账本」更深一层：v17 在给定结构上省资源，v18 改结构本身。

**直觉 3（跨端口共享是图，不是旋钮）**。v17 的 IP-45 把共享后端当成一个队列，调 chunk、调分辨率、调准入；但真正的决策是**共享哪些东西、共享多强、对谁共享**。共享模型权重几乎总是划算（省显存、可批处理）；共享校准统计在干净机队划算，但一个坏端口就能把全机队带偏（F70）；共享情景记忆只在任务/物体相似时划算。于是共享强度 κ 不应是全局常数，而应是**每条边的 VoC 的函数**：`κ* = argmax_κ E[K] − λ·Risk_contam(κ) − μ·Latency(κ)`。F70 的干净/rogue 反转正好证明「全共享」与「零共享」都不是最优，**鲁棒的部分池化**才是。

**直觉 4（双臂闭链是窄众模式，必须门控）**。F69 的数字很冷：双夹爪同时闭合只占 7.0%，而且只有 PlugInEthernet 的相对末端标准差低到 1.43 mm；PackDoll/ZipUp 的 42–52 mm 说明「双闭合」很可能只是两次独立抓取或滑移。若全局开启闭链虚拟夹具，就会在大多数任务上让两条臂互相打架——本轮快速仿真给出 always-closed 平均 **−4.5pp**，而按 15 帧观测门控可拿到 oracle 的 **+1.0pp**（在 PlugInEthernet 上是 +12pp）。所以正确的结构不是「双臂协同控制器」，而是**一个按技能/相位/观测选择 {独立、主从、闭链、交接、单臂} 的模式门**；闭链只在数据支持的任务上启用。

**直觉 5（v17 的「步数」是类别错误，必须当场纠正）**。F68 的公开榜单快照显示：step score 是 rubric 部分完成度，`step ≈ 0.510 + 1.321·success`，且 success 与 step 排名完全一致。v17 把「步骤分」当成动作步数去最小化，方向错了；更糟的是它会把「多走几步去完成一个 rubric 子目标」误判为浪费。v18 把目标改为**期望 rubric 信用** `E[K]=Σ v_j P_j`，并加一条「不丢已得分」约束：任何可能破坏已获得子目标的动作（掉落、碰撞、断链）都按信用损失计价。协作结构因此不是为了省步，而是为了**保护已得信用 + 解锁下一个子目标**。

**直觉 6（修剪：v17 最贵的三件套，恰好最不可验证）**。按规则 51，本轮把 **IP-48 四级热状态机降为二级时延/热守护**（官方观测无温度/电流，热代理不可验证）、把 **IP-50 完整离线 TO 收窄为闭链虚拟夹具/参考整形**（URDF/跟踪模型未备，块内开环会稀释全解收益），把省下的复杂度预算全部投给 Γ-Plane。v17 的 `g(N_steps)` 也被 IP-53 信用账本替换。**这不是砍能力，是把能力从「不可验证的估计量」搬到「可当场测量的结构量」。**

**本轮最大风险（一句话）**：官方协议里没有物理多机协作、双臂闭链又只占 7% 帧——若把 Γ-Plane 建立在「协作」这个词的想象上而不是这两条硬约束上，它会退化为「服务端共享缓存 + 一个窄众闭链模式」，收益被端口异构性与任务长尾吃掉；必须先以 E73（共享半径）与 E74（模式门控）证伪，再谈结构优化。

# 第 41 轮产物 · 创新点清单 v18：协作结构优化（CSO）——多机即多租户、多臂即多角色（「协作结构」横切层 Γ-Plane，四层架构 v6）

> 承接 v17（第 40 轮：热预算治理 × 步数感知规划 × 学习-TO 混合轨迹，Δ 资源平面 / 四层架构 v5）。本轮灵感词「多机协作 / 结构优化」。核实后两个词指向 v17 同一个未质疑的默认：**协作结构是给定的**。官方 README（F67）明确 N 台是独立机器人、独立 episode、独立端口，唯一真实的「多机协作」发生在共享推理后端（Approach 2）与跨机队统计；G1_Dex1 审计（F69）显示双臂同时运动 47.1%，但真正的闭链共持只占 7.0%。于是 v18 新增横切层 **Γ-Plane（协作结构平面）** 与 3 项核心 IP：**IP-51 跨端口共享图 / IP-52 双臂角色结构 / IP-53 信用账本**；同时**当场纠正 v17 对「步骤分」的类别错误**（F68），并修剪 IP-48 四级热机、IP-50 完整离线 TO。主轴从「单位物理成本的得分效率」推进到「**单位结构复杂度的可信得分**」。

## 0. 结论

- **Γ-Plane（本轮总纲）**：协作结构 `G=(V,E,τ,w)` 升格为一等优化变量；`V`={左臂, 右臂, N 个端口, 共享模块}，`τ`∈{COMPUTE, STAT, MEMORY, PHYS}，`w`=耦合强度。决策原则 **VoC（Value of Coupling）> 0**：只保留承载得分/可信度载荷的边；不承载载荷的共享/协调一律剪掉。
- **IP-51 FLEET-SHARING-GRAPH（P0 新增）**：跨端口共享图——共享 trunk/批处理/校准统计/检索记忆 vs 私有 episode 状态；层次化部分池化 + rogue 检测 + inlier pooling + 截止期批处理；**episode 状态永不共享**是硬不变量。直接对冲 F67 的并发、时延平滑性与状态隔离条款。
- **IP-52 DUAL-ARM-STRUCTURE（P0 新增）**：双臂角色/闭链结构——模式门 `{SINGLE, INDEP, LEAD_FOLLOW, CLOSED_CHAIN, HANDOFF}`；闭链模式用 `(T_rel, T_common)` + 虚拟夹具替代两条独立绝对目标；用 F69 的任务先验初始化门控；只在数据支持的 Plug/Insert/交接任务上启用。
- **IP-53 CREDIT-LEDGER（P0 新增，重构 IP-49）**：把 v17 的 `g(N_steps)` 换成 **rubric 信用账本** `E[K]=Σ v_j P_j − Σ v_j P(lose j)`；F68 证明 step score 是部分完成度且与 success 排名一致，所以 **success 仍是主排序代理**，信用账本用于保护已得分与子目标推进，不再最小化动作步数。
- **口径纠正（本轮最重要的事实修正）**：公开榜单快照上 `step ≈ 0.510 + 1.321·success`（R²=0.9814）、逐任务 b 均值 1.334（R² 均值 0.9925）、256 点零违例 `step<success`、排名与 success 完全一致。**v17 的「少步=高分」是错的；v18 不再奖励少步。**
- **修剪（规则 51）**：IP-48 四级热状态机 → P1 二级时延/热守护（无温度/电流遥测）；IP-50 完整离线 TO → P1 收窄为闭链虚拟夹具/参考整形；IP-49 的 `g(N_steps)` → 被 IP-53 替换；IP-45 多租户舱壁、IP-46 μ 分析、IP-47 ⊗、MAML 维持 P2。
- 通道诚实：无物理多机任务（F67）；榜单快照与官网「即将发布」并存（A39）；step score 定义由数据反推（A40）；rubric 权重未公开（A41）；N 未公布（A42）；URDF 未核实（A43）；无温度/电流/力矩观测（A44）。

## 3. 重点展开

### 3.1 v17 口径纠正：step score 是 rubric 信用，不是动作步数

v17 的定义 27 把步骤分写成 `g(N_steps)` 的单调减函数，并以 `E_score=Πp_s·g(N_steps)−λP(fail)` 做规划。F68 的公开快照推翻了这个口径：

- 模型级拟合：`step = 0.510 + 1.321·success`，R²=0.9814；
- 逐任务拟合：b 均值 1.334（1.19–1.40），R² 均值 0.9925（min 0.9715），a 均值 0.181；
- 256 个 (任务,模型) 点中 `step < success` 的违例为 0；
- success 与 step 的排名完全一致（fleet_results S0）。

因此 **step score 是「做对了多少 rubric 子目标」的部分完成度**，不是「用了多少动作步」。v18 的规划目标改为：

```
E[K(π)] = Σ_j v_j · P_j(π) − Σ_j v_j · P(lose j | π)
```

其中 `v_j` 是 rubric 子目标权重（未公开，A41；先用均匀/难度先验），`P_j` 是完成概率，`lose j` 是掉落/碰撞/断链等「把已得信用弄丢」的事件。**success 仍是主排序代理**（因为 `K≈a+bS`, b>0，且排名一致）；信用账本的价值在于 (a) 保护已得分，(b) 在部分完成的任务上做 tie-break，(c) 给协作结构一个可解释的收益单位。**步骤数不再被奖励或惩罚**；额外的动作只通过 Δ-Plane 的时延/热/墙钟成本计价。

**推论**：v17 的「步数感知规划」应改名为「**信用感知规划**」；「少步」不是目标，「不丢分、多拿子目标」才是。任何协作结构的收益都必须用 `ΔE[K]` 与可信度指标来审计，不能用「省了几步」来论证。

### 3.2 Γ-Plane：协作结构作为一等优化变量

**定义 29（协作结构）**：`G=(V,E,τ,w)`，其中
- `V = {L,R} ∪ {p_1..p_N} ∪ M`，`M` 为共享模块（trunk、batch scheduler、calibration、retrieval memory、credit prior）；
- `E ⊆ V×V`，边类型 `τ(e) ∈ {COMPUTE, STAT, MEMORY, PHYS}`；
- `w(e) ∈ [0,1]` 为耦合强度（共享参数比例/池化强度/虚拟夹具刚度）；
- **状态隔离约束**：对任意两个端口 `p_i,p_j`，不存在携带 episode 状态的边；`STAT`/`MEMORY` 边只能携带**聚合统计**或**已完成 episode 的过去数据**，且更新必须是因果的（不得使用当前 episode 的未来观测）。

**定义 30（价值耦合 VoC）**：对候选边 `e∉E`，
```
VoC(e|G) = ΔE[K] − λ_L·ΔCVaR_α(L_p99) − λ_C·ΔRisk_contam
           − λ_R·ΔIrregularity − λ_K·ΔCost
```
`K` 为信用，`L_p99` 为时延，`Risk_contam` 为共享统计被坏端口污染的风险，`Irregularity` 为动作统计异常（F67 可信度条款），`Cost` 为显存/算力/复杂度。**只加入 VoC>0 的边**；删除 VoC<−h 的边（迟滞 h 防抖）。

**定义 31（风险敏感机队目标）**：
```
max_G  E[K(G)] − β·CVaR_α(K_loss) − λ_L·CVaR_α(L_p99) − λ_C·sup_rogue |contam|
s.t.   state_isolation(G),  P(L > deadline) ≤ δ,  |E| ≤ B_struct
```

**命题 P56（隔离组合）**：若所有 `STAT/MEMORY` 边只传递已完成 episode 的聚合统计或严格过去的因果统计，且每个端口有独立的可变 episode 容器，则端口 `i` 的当前动作不依赖端口 `j` 的当前/未来观测；联合轨迹分布与独立服务等价。证明要点：在概率图模型中，切断所有携带当前 episode 状态的路径后，`do(o_i^t)` 与 `a_j^t` d-分离。

**命题 P57（污染界）**：若共享统计使用 median-of-means / trimmed inlier pooling，且坏端口比例 `ρ<1/2`，则单个 rogue 端口对共享统计的影响被截断；在 inlier 集合上，偏差界为 `O(σ√(log(1/δ)/n_inlier))`，最坏情况由 `ρ` 与截断阈值控制。F70 的 clean/rogue 反转与本节合成检查（§3.8）都支持这一结论。

**命题 P58（VoC 贪心）**：若 `E[K]` 对边集合的边际增益是次模的、成本是模的，则按 VoC 降序贪心加边，在基数约束 `|E|≤B_struct` 下达到 `(1−1/e)` 近似。次模性是**经验假设**（收益递减），需在 E73/E75 中验证；若不成立，退化为局部搜索，不宣称近似比。

**算法（Γ-Plane 主循环）**：
```
每 episode 边界 / 每 K 步 / 检测到场景切换：
  1. 采集：每端口时延 EWMA/p99、动作离群率、校准残差、任务/技能/相位、Δ 账本
  2. 候选边：共享 trunk(默认)、动态批处理、校准统计、检索记忆、闭链模式、交接
  3. 对每条候选边估计 VoC（离线先验 + 在线观测；小样本用贝叶斯平滑）
  4. 贪心选边，受状态隔离/截止期/显存/复杂度约束；与当前 G 比较，带迟滞
  5. 实例化：共享模块 + 每端口适配器 + 双臂模式 + chunk 档位
  6. 执行；更新信用账本与污染检测器；记录结构决策（可审计）
```

### 3.3 IP-51 FLEET-SHARING-GRAPH（跨端口共享图）

**IP 卡片（六字段）**：
- **动机**：F67 明确允许 Approach 2（共享后端），且不同端口可能并发；F70 证明共享校准在干净机队有益、但会被 rogue 端口污染；F71 证明 chunk 粒度必须随 N 变。v17 只把共享当队列，没有把「共享什么/多强」作为结构决策。
- **与现有方案差异**：现有服务化方案默认「全共享」或「全隔离」；DC-Ada（F72）做每机器人观测适配但不动共享图；Fleet Experience（F72）做跨机队经验学习但不处理评测期隔离与污染。我们把**共享图 + 污染检测 + 隔离不变量**合成一个可在线决策的结构控制器。
- **技术可行性**：共享 trunk + 每端口 LoRA/adapter 是成熟工程；校准统计用层次贝叶斯/稳健聚合；动态批处理用 deadline-aware 队列；所有组件 <1ms/步（除推理本身）；无需改官方接口。
- **所需资源**：E73 遥测（N∈{2,4,8}，异质度 τ、rogue 比例 ρ）；每端口状态容器；共享统计存储；显存预算表。
- **落地步骤**：① 建每端口状态容器与隔离测试；② 共享 trunk + 私有 adapter；③ 校准统计的 inlier pooling 与 rogue 检测；④ deadline-aware 批处理；⑤ E73/E75 验收；⑥ 接入 IP-54。
- **风险**：共享污染（→inlier pooling + 保守 κ）；端口异构（→每端口 adapter + 观测归一化）；批处理增加尾延迟（→deadline 硬截断 + 隔离旁路）；状态泄漏（→P56 不变量 + 单元测试）。

**共享图节点/边表**：

| 节点/边 | 类型 | 默认 | 共享强度 | 依据 |
|---|---|---|---|---|
| 共享 trunk（视觉/语言/动作骨干） | COMPUTE | 总是共享 | w=1 | 显存/算力；F67 Approach 2 |
| 每端口 adapter（LoRA/RARA） | COMPUTE | 私有 | w=0 | 异构机器人/相机；DC-Ada |
| 共享校准统计（分位数/偏移） | STAT | 条件共享 | κ∈[0,1] | F70：clean 有益、rogue 有害 |
| 共享检索记忆（演示/技能） | MEMORY | 仅任务/物体相似时 | w∈{0,1} | 跨任务迁移；F72 Fleet Experience |
| 共享信用先验（p_s/难度） | STAT | 总是共享（聚合） | w=1 | F68 32 任务先验 |
| 动态批处理调度 | COMPUTE | 总是共享 | w=1 | F71：N 越大越需要 |
| episode 状态（历史/图像/动作） | — | **绝不共享** | w=0 | F67 硬条款 |

**共享强度决策**：
```
κ* = argmax_κ  E[K | κ] − λ·Risk_contam(κ) − μ·Latency(κ)
Risk_contam(κ) = P(rogue) · E[|θ̂_shared(κ) − θ_true|]
```
用层次贝叶斯/经验贝叶斯估计 `κ`；用 median/MAD 或 max-deviation 检测 rogue；检测到 rogue 时只在 inlier 集合上池化，rogue 端口回退到私有校准。**F70 的 clean/rogue 反转说明不存在全局最优 κ**，必须在线选择。

**算法（FSG）**：
```
输入：N 个端口的请求、每端口状态 s_i、共享统计 D、截止期 d_i
循环：
  对每个就绪端口 i：
    if 需要校准：κ_i = select_kappa(D, rogue_score(D))
       θ̂_i = (1-κ_i)·θ̂_i^private + κ_i·θ̂_inlier
    if 可批处理：把 i 放入当前 batch，直到 batch 满或最早截止期将至
  推理：共享 trunk 一次 forward（batch），每端口 adapter 分别输出
  若某端口将错过 d_i：从 batch 移除并走轻量分支（隔离旁路），不拖累其他端口
  更新共享统计（仅用已完成 episode 的聚合；因果、去标识）
  维护：每端口独立 reset/历史容器；共享模块只读或聚合写
```

**正确性/风险**：P56 保证隔离；P57 给出污染界；F71 的 S3 证明自适应 chunk 能在 N=3..20 维持 SLO。**最大风险**：共享污染与端口异构导致「共享不如隔离」；E73 若显示共享的 worst-port 收益为负，则 FSG 退化为「共享 trunk + 全私有校准」。

### 3.4 IP-52 DUAL-ARM-STRUCTURE（双臂角色/闭链结构）

**IP 卡片（六字段）**：
- **动机**：F69 证明双臂同时运动 47.1%，但双夹爪同时闭合仅 7.0%；真正闭链（PlugInEthernet 1.43mm）与「两次独立抓取/滑移」（PackDoll 51.9mm）必须区别对待。v17 把双臂当成 14 个独立关节目标，没有「角色/闭链」结构。
- **与现有方案差异**：CRISP（F72）用闭链约束进 NMPC，但需要全身动力学/力矩；Co-VLA（F72）用 shared+residual latent 学协调，但不做模式门；我们做的是**离散模式门 + 位置级虚拟夹具**，诚实于官方只给 joint/ee 目标、无力的接口。
- **技术可行性**：模式门用观测（双夹爪闭合、相对 EE 速度/距离、任务/技能/相位）即可；闭链虚拟夹具在 EE 空间用 `T_rel` 约束，无需力矩；MuJoCo 可预校验；G1 双臂 7-DoF 冗余可用于角色分配。
- **所需资源**：F69 审计先验；URDF/运动学（A43：缺失时退化为 EE 相对约束，不做自碰撞）；少量真机/仿真验证（E77）；模式门训练数据可从公开演示自监督构造。
- **落地步骤**：① 用 F69 初始化每任务模式先验；② 实现 5 模式门（规则+小分类器/bandit）；③ 闭链虚拟夹具 `(T_rel,T_common)`；④ 交接契约（释放/接收时序、夹爪窗口）；⑤ MuJoCo 门；⑥ E74/E77 验收。
- **风险**：模式门假阳性（→保守阈值 + 代价敏感）；闭链在非刚性任务上打架（→只在低相对速度/低 std 任务启用）；URDF 缺失（→退化为 EE 相对约束 + 软限位）；无力控导致接触任务精度不足（→位置级虚拟夹具 + 小增益，诚实降级）。

**模式表**：

| 模式 | 何时用 | 动作参数化 | F69 先验（12 任务） | 风险 |
|---|---|---|---|---|
| SINGLE_L / SINGLE_R | 单臂任务；另一臂可作观察/稳定 | 单臂绝对目标 | 单左 14.95% / 单右 22.29% 闭合帧 | 另一臂闲置浪费 |
| INDEP | 双臂在共享工作空间但无接触 | 两条独立绝对目标 | 双臂同时运动 47.1% | 自碰撞/抢道 |
| LEAD_FOLLOW | 一件物体、一臂主导、一臂辅助 | 主臂绝对 + 从臂相对偏置 | 多数非接触协调 | 角色切换抖动 |
| CLOSED_CHAIN | 准刚性共持/插入/双手拧 | `(T_rel, T_common)` + 虚拟夹具 | 双闭合 7.0%；仅 PlugInEthernet 1.43mm 达刚性 | 非刚性任务打架 |
| HANDOFF | 臂间交接 | 释放/接收时序 + 夹爪窗口 | 顺序交接常见 | 掉落/时序错 |

**闭链参数化**：
```
独立：a = (T_L, T_R) ∈ SE(3)^2
闭链：a = (T_common, T_rel)，T_rel = T_L^{-1} T_R
目标：T_rel → T_rel^*,  T_common → T_common^*
虚拟夹具：F_rel = −K_vf · log(T_rel^{-1} T_rel^*)  （位置级，非力矩）
```
`K_vf` 按任务刚度调度：Plug/Insert 用高刚度保相对位；FoldTowel 用低刚度允许形变；PackDoll 若相对 std 大则禁用闭链。**闭链模式的收益不是省步，而是减少双臂内部对抗、提高相对位精度、保护已抓取的信用。**

**模式门（代价敏感）**：
```
特征：双夹爪闭合概率、相对 EE 速度/距离的 k 帧均值与 std、
      任务/技能/相位先验、语义图物体尺寸、IP-30 验证器置信度
决策：m* = argmax_m E[K | m] − λ_c·Risk(m) − λ_s·SwitchCost(m,m_prev)
约束：m=CLOSED_CHAIN 仅当 P(quasi-rigid) ≥ τ 且相对 std ≤ s_max
```
用 F69 的每任务 std 初始化 `P(quasi-rigid)`；在线用少量 co-hold 帧更新。**假阳性代价高**（always-closed 平均 −4.5pp），所以阈值保守。

**正确性/风险**：P59（闭链精度）——在相对位参数化下，两条臂的独立跟踪噪声不再直接相加为相对误差；相对误差由虚拟夹具刚度和 `T_rel` 观测噪声决定，故在同等等级跟踪噪声下 `E[‖T_rel−T_rel*‖]` 不大于独立模式。**最大风险**：模式门在未见任务上误判，或闭链在柔性物体上造成滑移；E74/E77 必须先证伪。

### 3.5 IP-53 CREDIT-LEDGER（信用账本）

**IP 卡片（六字段）**：
- **动机**：F68 证明 step score 是 rubric 部分完成度；v17 的 `g(N_steps)` 是类别错误。信用账本把「已得分的保护」与「下一子目标的推进」显式化，并与 F67 的可信度条款（动作规律性）联动。
- **与现有方案差异**：SayCan/GAVEL 优化语义可行性；v17 优化步骤数；我们优化**期望 rubric 信用 − 不可逆损失**，且把信用作为协作结构的收益单位。
- **技术可行性**：rubric 子目标可从任务名/演示/官方 94 个评分点近似（A41 未公开）；用 IP-28v2 进度 + IP-30 VLM 判别 + IP-33 守护做证据；小状态机/账本 <1ms。
- **所需资源**：32 任务 rubric 先验（公开榜单统计 + 任务描述）；演示数据的分段/子目标弱标签；失败记忆库。
- **落地步骤**：① 建 32 任务 rubric 草图（2–5 子目标/任务，F68 直方图 2:11/3:14/4:5/5:2）；② 信用账本与证据融合；③ 损失惩罚（掉落/碰撞/断链）；④ 规划器接 `E[K]`；⑤ E76 校准；⑥ 在线更新 p_s。
- **风险**：rubric 权重未知（→均匀/难度先验 + 稳健优化）；验证器误差（→只作软证据，硬约束仍由 CBF）；信用 hacking（→不直接优化代理，只用于排序/保护）；跨任务迁移（→分桶 + 贝叶斯平滑）。

**算法**：
```
维护：每个子目标 j 的信念 b_j∈[0,1]，权重 v_j，信用 C=Σ v_j b_j
每步：用 IP-28v2/IP-30/IP-33 更新 b_j；检测不可逆事件 → 扣 v_j
规划：π* = argmax E[C(π)] − λ·P(irreversible loss)
执行：若动作可能使已得 b_j 下降（掉落/碰撞/断链）→ 触发 IP-33 否决或 IP-52 模式切换
重规划：若 E[ΔC] > 重规划成本（时延/热/风险）才重规划
```
**正确性**：P60（信用-成功率序等价）——若 `K=a+bS`（b>0）且排名一致，则按 `E[K]` 排序与按 `E[S]` 排序在任务级一致；信用账本不改变主排序，只提供子目标级 tie-break 与损失保护。**最大风险**：rubric 近似错误导致「优化了不存在的子目标」；E76 必须先验证信用与公开 step score 的单调关系。

# ===== 离线：双臂模式先验 + 信用账本初始化 =====
def build_dual_arm_prior(audit, tasks):
    # F69: per-task both_closed / cohold_std / arm_corr
    prior = {}
    for t in tasks:
        s = audit[t].get("cohold_rel_dist_std_mm")
        prior[t] = {
            "p_quasi_rigid": 1.0 if (s is not None and s <= 5.0) else 0.05,
            "cohold_std_mm": s,
            "p_closed": audit[t]["both_closed"],
        }
    return prior

def build_credit_ledger(task_profile):
    # 32 tasks, 2-5 rubric subgoals; weights unknown -> uniform/difficulty prior
    return {t: [{"v": 1.0 / n, "evidence": None} for _ in range(n)]
            for t, n in task_profile.items()}

# ===== 运行期：Γ-Plane + Δ-Plane + 信用执行 =====
def act_v18(obs, state):
    # 1. Δ 账本（v17 二级守护）
    ledger = update_ledger(H_gpu=telemetry(), S_used=state.steps, L=L_ewma)
    knobs = latency_guard(ledger)          # NOMINAL / CONSERVATIVE only

    # 2. Γ-Plane：只在边界/场景切换/失败后重选结构
    if state.need_structure:
        G = structure_controller(
            ports=state.fleet, arms=("L", "R"),
            candidates=fleet_edges() + arm_modes(state.task_ctx),
            ledger=ledger, credit=state.credit, budget=state.budget)
        state.G = G
        state.share_edges, state.arm_mode = G.share_edges, G.arm_mode

    # 3. 信用规划（IP-53）
    if state.need_plan:
        state.plan = credit_planner(obs.language, state.semantic_map,
                                    state.credit, state.fail_memory,
                                    budget=knobs, structure=state.G)

    # 4. 双臂结构（IP-52）
    mode = dual_arm_gate(obs, state.task_ctx, state.arm_mode,
                         prior=state.dual_prior, credit=state.credit)
    if mode == "CLOSED_CHAIN":
        task = closed_chain_task(state.plan, obs, K_vf=state.K_vf)
    else:
        task = midlevel(state.plan, obs, budget=knobs, structure=state.G)

    # 5. 热启动 + 收窄精修（IP-50 仅闭链/参考整形；否则 VLA 直出）
    warm = stream_policy_head(state.plan.skill, obs)
    refined = structure_refine(task, warm, mode=mode,
                               envelopes=state.semantic_map.objects,
                               deadline=0.5 * chunk_window(knobs))
    state.traj = refined if refined is not None else warm

    # 6. 执行 + 兜底（官方 chunk 语义）
    chunk = state.traj.next_chunk(knobs.T_a_eff)
    if not guard.cbf_check(chunk):
        chunk = resample_or_fallback(state, r=2)
    q_cmd = adapt(chunk, control_space=state.control_space)

    # 7. 信用/失败更新
    state.credit = update_credit(state.credit, obs, chunk,
                                 verifier=state.vlm, guard=guard)
    if failure_monitor(obs) > TAU_FAIL:
        state.fail_memory.log(state.plan.skill, obs.focus, state.fail_sig)
        state.need_structure = True      # 结构可能也要变（模式/共享）
        state.need_plan = True
    return q_cmd

# ===== IP-51 共享图 =====
def structure_controller(ports, arms, candidates, ledger, credit, budget):
    G = default_structure()              # shared trunk + private state + INDEP
    cand = estimate_voc(candidates, G, ledger, credit)
    for e in sorted(cand, key=lambda x: -x.voc):
        if e.voc <= 0: break
        if not constraints_ok(G + e, budget, ledger): continue
        if e.voc > threshold_with_hysteresis(e, G): G = G + e
    return G

def fleet_serve(requests, shared, per_port):
    # per_port[i] holds episode history; shared holds only aggregate stats
    batch = deadline_aware_batch(requests, deadline=chunk_window())
    out = shared.trunk(batch)            # one forward
    for i, r in enumerate(batch):
        κ = select_kappa(shared.calib, rogue_score(shared.calib))
        out[i] = per_port[i].adapter(out[i], κ)   # private adapter
    update_shared_stats_after_episode(shared, completed_only=True)
    return out

**本轮快速机制检查（合成，非榜单证据；脚本 exp/r41_cso_sim.py，seed 20261110）**：

- **A 双臂结构门控**：12 任务中仅 PlugInEthernet 判为准刚性（1.43mm）；always-INDEP Δ=0；always-CLOSED 平均 **−4.5pp**；oracle **+1.0pp**；k=5/15/30 帧门控 **+0.99/+1.00/+1.00pp**。**读法**：闭链是窄众高价值模式，全局开启会伤大多数任务；15 帧门控即可拿到几乎全部 oracle 收益。
- **B 机队共享半径**（N=8，τ=0.5，σ=1，1 observation/port）：
  - clean：isolated MSE 0.966；κ=0.75 0.292；full 0.329；adaptive 0.371；
  - one rogue：isolated 1.067；full **4.275**；adaptive（max-deviation + inlier pooling）**0.774**（worst 3.819）。

- 这两个检查只证明**机制方向**，不证明榜单收益；真实验收必须走 E73/E74。

**降级机制 v4**：
- E73 失败（共享无收益/污染不可控）→ FSG 退化为「共享 trunk + 全私有校准 + 静态 chunk」。
- E74 失败（门控无增益/误判多）→ DAS 退化为 INDEP + 仅交接模式；闭链关闭。
- E77 失败（虚拟夹具无精度增益）→ 仅保留模式门做交接/角色，不做闭链。
- E76 失败（信用不可校准）→ 回退 success-only 目标，信用账本仅作日志。
- E75 失败（批处理尾延迟）→ 每端口独立 chunk，不做动态 batch。
- 全部失败 → 回退 v17 基线 + 仅保留 F67 的状态隔离与二级时延守护。

- **52（新增）：协作结构一等原则**——协作结构 `G=(V,E,τ,w)` 是全架构一等优化变量；多机只做「多租户共享后端 + 机队统计」，不做物理多机任务；多臂只做「角色/模式结构」，不假设全时闭链；每个结构决策必须可被官方接口/公开数据审计。
- **53（新增）：隔离-共享分离原则**——episode 状态永不共享；只允许聚合统计/参数/记忆共享；共享更新必须因果（不得用当前 episode 未来观测）；共享统计必须有 rogue 检测与污染界；状态隔离是不可谈判的硬不变量。
- **54（新增）：价值耦合原则**——只保留 VoC>0 的协作边；协作边必须同时计入得分/信用、时延平滑性、动作规律性、污染风险与复杂度；结构决策带迟滞，不每步重选；结构复杂度有上界。
- **55（新增）：评分口径校准原则**——「步骤分」先按 rubric 部分完成度处理，不按动作步数；任何内部评分代理必须用公开榜单/本地评测校准；success 是主排序代理，信用账本只做子目标推进/损失保护/tie-break；口径错误优先于模型错误被修正。

**当前最值得押注**：**IP-51 FLEET-SHARING-GRAPH（跨端口共享图）**——它是本轮唯一同时满足「官方明确允许、可被 F67 的时延/隔离条款直接审计、且能用 E73/E75 快速证伪」的结构优化点；DAS 的任务增益更尖但更窄（仅 7% 帧），CL 是口径修正而非新能力。先让 FSG 在 N≥8 的共享后端上把 worst-port 与 p99 CV 打下来，再把 DAS 作为接触任务的精度放大器接入 Γ-Plane。

**本轮最大风险（一句话）**：官方协议里没有物理多机协作、双臂闭链又只占 7% 帧——若把 Γ-Plane 建立在「协作」这个词的想象上而不是这两条硬约束上，它会退化为「服务端共享缓存 + 一个窄众闭链模式」，收益被端口异构性与任务长尾吃掉；必须先以 E73（共享半径）与 E74（模式门控）证伪，再谈结构优化。
