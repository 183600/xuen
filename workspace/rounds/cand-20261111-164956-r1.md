# 第 55 轮（承接第 54 轮 v31 GroundEdge-GenSim+++；灵感循环第 6 轮；本轮灵感：「奖励设计」×「痛点分析」）

> 第 54 轮已把技能组合升级为动作-鲁棒性双证书（`α_S` / `A_cert` / `γ_ce` / `δ_a` / `J`），形成“云规划—边校验—反向解释—重剖分”闭环。本轮把视角前移到**更上游的目标塑造**：系统该在“哪里”获得“多大”的激励？核心矛盾：**H22**：`ρ`、`α`、证书都是**否决式安全件**，只说明“不能做什么”，不说明“最该改善什么”，学习与规划对真实痛点无的放矢；**H23**：痛点是部署分布上的长尾失败，而奖励是人工设定的短视目标，二者错位时策略会以**奖励黑客**方式抬升指标、却把痛点**位移**到未测量盲区。

## 0. 直觉与动机

**灵感 1（痛点不是失败清单，而是可估计的痛点场）**
直觉：痛点分析若只产出“失败 case 列表”，对训练与规划几乎无用。真正的痛点应是定义在部署上下文空间 `C = T × A × E`（任务 × 动作 × 环境）上的**痛点场** `Π : C → ℝ≥0`。借用 FMEA 的四因子，把“哪里疼、多疼、多难发现、多难恢复”编码为一个非负标量：频率 `f`、严重度 `s`、可检测性 `d`、可恢复性 `r`。这样痛点从“讲故事”变成“可估计、可加权、可微分”的对象，才能进入奖励。

**灵感 2（奖励设计 = 痛点场的逆问题）**
直觉：不要再手工拼 `r = w₁·success + w₂·...`。把奖励设计当成**逆问题**：寻找一个 `R`，使策略改进方向恰好是痛点场的下降方向。最干净的构造是把痛点场当**势函数**做势函数型奖励塑形（PBRS）：`Φ(c) = -Π(c)`，`F(s,a,s') = γΦ(s') - Φ(s)`。PBRS 的**策略不变性**（Ng et al.）给出严谨锚点：塑形只改变学习信号密度，不改变最优策略；真实目标由 `Π` 承担，塑形只负责把痛点的稠密梯度铺到时间轴上。

**灵感 3（奖励黑客的绊线 = 奖励与痛点的散度）**
直觉：正因为 PBRS 对给定势函数策略不变，任何“奖励升、痛点不降”都是**规格博弈**的强信号。定义**黑客残差** `H(π) = max(0, ΔR - κ·(-ΔΠ))`：奖励增益若不能兑换成等比例的痛点下降，就触发绊线。奖励于是从“越高越好的标量”变成**带对齐证书 `C_R` 的受约束对象**。

**灵感 4（痛点驱动的课程与主动挖掘）**
直觉：痛点场天然给出采样分布 `q(c) ∝ Π̂⁺(c)^β / cost(c)` 和课程顺序（先高痛点、再低痛点、最后不确定盲区）。这把“痛点分析”从事后复盘升级为**主动实验设计**：预算优先投给“最疼且最不确定”的区域（悲观上界 UCB），避免在已知安全区刷分。

**灵感 5（跨层与跨域奖励一致性）**
直觉：云端用粗上下文痛点场、边端用细上下文痛点场；若二者在动作重叠区 `C_core` 上诱导的**偏好序不一致**，云边计划会互相拆台（H21 的奖励版本）。迁移到新域时痛点场会漂移，旧奖励可能“奖励错误行为”。故奖励证书必须携带**跨层一致性**与**跨域迁移有效性**两项，接上第 54 轮的 `A_core` 与联合证书 `J`。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（痛点场）**
上下文空间 `C = T × A × E`。痛点场 `Π : C → ℝ≥0`：
```
Π(c) = f(c)·s(c)·(1 + λ_d·(1 - d(c)))·(1 + λ_r·(1 - r(c)))
```
其中 `f` 为部署频率，`s` 为严重度（归一化损失），`d∈[0,1]` 为可检测性（越大越易发现），`r∈[0,1]` 为可恢复性，`λ_d, λ_r ≥ 0` 惩罚“难发现/难恢复”。证据来自第 54 轮 `Explain` 回传、TRO/REX 轨迹与仿真反例。估计量给出置信带 `[Π⁻, Π⁺]`，悲观上界 `Π̂⁺` 用于保守设计。

**定义 122（痛点势与疼痛感知回报）**
势函数 `Φ(c) = -Π(c)`，塑形项 `F(s,a,s') = γΦ(s') - Φ(s)`。疼痛感知回报 `R(s,a,s') = U_task(s,a) + F(s,a,s')`，其中 `U_task` 为任务成功项。沿轨迹的痛点积分定义为 `Pain(τ) = Σ_t Π(c_t)`。

**定义 123（奖励-痛点对齐证书）**
`C_R = (R_spec, Π_ref, δ_align, cov_pain, anti_hack, ρ_R)`：
- `R_spec` 奖励规范（含 `Φ`）；
- `Π_ref` 参考痛点场（带 `Π⁻,Π⁺`）；
- `δ_align > 0` 对齐裕度：在痛点活跃集 `C⁺={c:Π(c)≥ε}` 上，改进方向的协方差满足 `⟨∇_θ R, ∇_θ Π⟩ ≤ -δ_align`；
- `cov_pain = Π(C⁺ 被奖励项覆盖)/Π(C)` 痛点质量覆盖率；
- `anti_hack` 绊线阈值 `(η, κ)`；
- `ρ_R` 奖励对上下文扰动 `‖δc‖≤δ` 的 Lipschitz 稳定性。
若 `dom=in`、`cov_pain ≥ θ_cov`、`δ_align ≥ δ_min` 且 `H≤η`，则奖励可部署。

**定义 124（奖励黑客残差与绊线）**
相对参考策略 `π₀`：
```
H(π) = max(0, ΔR(π) - κ·(-ΔΠ(π)))
ΔR = E_π[R] - E_{π₀}[R],  ΔΠ = E_π[Π] - E_{π₀}[Π]
```
当 `ΔR>0 ∧ ΔΠ≥0` 时必有 `H ≥ ΔR > 0`。绊线条件：`H > η` 或出现“奖励升而 `Π` 不降”。判定为规格博弈，拒绝把 `π` 纳入部署候选。

**定义 125（痛点驱动采样与课程）**
`q(c) = exp(β·(Π̂⁺(c) - λ_u·u(c))) / cost(c)`，`u(c)` 为 `Π` 的估计不确定度，`cost` 为采样成本。课程级 `L_k = {c : Π̂⁺(c) ∈ [ε_k, ε_{k+1})}`，从高痛点到低痛点、从低不确定到高不确定推进。

**定义 126（跨层/跨域奖励一致性证书）**
跨层：在 `C_core` 上抽轨迹对 `(τ₁,τ₂)`，若 `sign(R_c(τ₁)-R_c(τ₂)) ≠ sign(R_e(τ₁)-R_e(τ₂))` 的比率 `≤ δ_pref`，则云边偏好一致。跨域：源/目标痛点场秩相关 `τ_K(Π_src, Π_tgt) ≥ θ_tr` 且奖励在目标域通过**因果不变性检验**（干预后偏好不变），才允许 `R_src` 迁移。

## 2. 关键算法 伪代码

### IP-121 PMF（Pain-field Map）

```python
def estimate_pain_field(evidence, contexts, lam_d, lam_r, prior, alpha=0.05):
    Pi_hat, Pi_lo, Pi_hi = {}, {}, {}
    for c in contexts:
        f, s, d, r = evidence.fmea_stats(c)          # 频率/严重度/可检测/可恢复
        base = f * s * (1 + lam_d*(1-d)) * (1 + lam_r*(1-r))
        lo, hi = evidence.confidence_band(c, prior, alpha)   # Beta/自助法
        Pi_hat[c] = base
        Pi_lo[c], Pi_hi[c] = base*lo, base*hi
    return PainField(Pi_hat, Pi_lo, Pi_hi)

def pain_mass(field, region):
    return sum(field.Pi_hat[c] for c in region)
```

### IP-122 PAR（Pain-Aligned Reward）

```python
def synthesize_reward(field, task_spec, gamma):
    Phi = {c: -field.Pi_hi[c] for c in field.Pi_hat}     # 悲观势
    def R(s, a, s2):
        return task_spec.reward(s, a) + gamma*Phi.get(s2, 0.0) - Phi.get(s, 0.0)
    cov = pain_mass(field, task_spec.active_region) / max(pain_mass(field, field.Pi_hat), 1e-9)
    return R, RewardSpec(Phi=Phi, coverage=cov)
```

### IP-123 RHC（Reward Hacking Checker）

```python
def reward_hacking_check(pi_new, pi_ref, R, field, kappa, eta, n_roll):
    dR  = eval_return(pi_new, R, n_roll) - eval_return(pi_ref, R, n_roll)
    dPi = eval_pain(pi_new, field, n_roll) - eval_pain(pi_ref, field, n_roll)
    H = max(0.0, dR - kappa*(-dPi))        # 只有 dPi<0 才允许兑换奖励增益
    if H > eta or (dR > 0 and dPi >= 0):
        return ('tripwire', H, dR, dPi)
    return ('aligned', H, dR, dPi)
```

### IP-124 PDC（Pain-Driven Curriculum）

```python
def pain_curriculum(field, budget, beta, lam_u, cost):
    q = {}
    for c in field.Pi_hat:
        u = field.Pi_hi[c] - field.Pi_lo[c]
        q[c] = exp(beta*field.Pi_hi[c] - lam_u*u) / max(cost(c), 1e-9)
    Z = sum(q.values()); q = {c: v/Z for c, v in q.items()}
    order = sorted(q, key=lambda c: -field.Pi_hi[c])
    return q, order, allocate(order, q, budget)
```

### IP-125 CLC（Cross-Layer reward Consistency）

```python
def cross_layer_consistency(R_c, R_e, C_core, n_pairs, delta_pref):
    viol = 0
    for t1, t2 in sample_pairs(C_core, n_pairs):
        if sign(R_c(t1)-R_c(t2)) != sign(R_e(t1)-R_e(t2)):
            viol += 1
    return ('ok' if viol/n_pairs <= delta_pref else 'reject', viol/n_pairs)
```

### IP-126 RTC（Reward Transfer Certificate）

```python
def reward_transfer_cert(R_src, Pi_src, Pi_tgt, theta_tr, delta_align):
    tau = kendall_tau(Pi_src, Pi_tgt)
    if tau < theta_tr:
        return ('reject', 'pain_shift', tau)
    if not causal_invariance(R_src, Pi_tgt, delta_align):
        return ('reject', 'causal_mismatch')
    return ('ok', RewardTransferCert(tau, Pi_tgt))
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| PMF | O(|C|·(n_ev + b·B)) | O(|C|) | 置信带覆盖、FMEA 四因子可估 |
| PAR | O(|C|) | O(|C|) | Φ 因果有效、PBRS 策略不变 |
| RHC | O(n_roll·T) | O(T) | ΔR/ΔΠ 同分布估计、κ 校准 |
| PDC | O(|C| log|C|) | O(|C|) | q 归一、成本上界 |
| CLC | O(n_pairs·log n_pairs) | O(n_pairs) | 偏好本体共享 |
| RTC | O(|C| log|C|) | O(|C|) | 秩相关 + 因果不变 |

**正确性定理（Pain-Aligned Reward Soundness）**
假设第 54 轮 (A26)–(A28) 成立；**(A29)** 悲观痛点估计 sound：`Π̂⁺ ≥ Π_true` 以概率 `1-α`；**(A30)** 在 `Φ=-Π̂⁺` 上 PBRS 策略不变；**(A31)** 奖励证书满足 `δ_align>0` 且在痛点活跃集上 `⟨∇R,∇Π⟩ ≤ -δ_align`。则对任意策略改进 `ΔR > η`：
```
Π_true(π) ≤ Π_true(π₀) - (ΔR - η)/κ + 2·ε_Π,   ε_Π = ‖Π_true - Π̂⁺‖∞
```
从而 `P(痛点未下降) ≤ α + P(H>η) + P(ε_Π > (ΔR-η)/(2κ))`。**组合前提是“痛点场可信 + 势函数因果 + 对齐非循环”。**

## 6. 本轮最大风险

**一句话**：把奖励设计建立在痛点场上，看似让“安全件”变成了“目标件”，但其 soundness 依赖**痛点场的完备性与因果有效性**——一旦 `Π̂` 漏掉长尾痛点、或势函数在仿真与真实间发生因果错配，PBRS 的“策略不变性”反而会提供虚假安全感，策略将把痛点从被测量的区域**位移**到盲区，形成“指标漂亮、部署仍疼”的奖励黑客闭环，故必须以**悲观上界痛点场 + 主动盲区挖掘 + 独立反事实绊线**为硬约束，宁可奖励保守，也不把“痛点场覆盖不到的安静”当作安全。

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| PMF | O(|C|·(n_ev+b·B)) | O(|C|) | 置信带覆盖 ≥ 1-α |
| PAR | O(|C|) | O(|C|) | PBRS 策略不变、Φ 因果 |
| RHC | O(n_roll·T) | O(T) | ΔR/ΔΠ 同分布、κ 校准 |
| PDC | O(|C| log|C|) | O(|C|) | q 归一、成本有界 |
| CLC | O(n_pairs log n_pairs) | O(n_pairs) | 偏好本体共享 |
| RTC | O(|C| log|C|) | O(|C|) | 秩相关 + 因果不变 |

**正确性定理（Pain-Aligned Reward Soundness）**
承接第 54 轮 (A26)–(A28)；新增 **(A29)** 悲观估计 sound `Π̂⁺≥Π_true` w.p. `1-α`；**(A30)** 在 `Φ=-Π̂⁺` 上 PBRS 策略不变；**(A31)** `δ_align>0` 且痛点活跃集上 `⟨∇R,∇Π⟩≤-δ_align`。则对 `ΔR>η`：
```
Π_true(π) ≤ Π_true(π₀) - (ΔR-η)/κ + 2ε_Π
P(痛点未降) ≤ α + P(H>η) + P(ε_Π > (ΔR-η)/(2κ))
```
关键：**痛点场可信、势函数因果、对齐非循环**三者缺一不可。

## 5. 本轮最大风险

**一句话**：把奖励设计建立在痛点场上，看似让“安全件”变成了“目标件”，但其 soundness 依赖**痛点场的完备性与因果有效性**——一旦 `Π̂` 漏掉长尾痛点、或势函数在仿真与真实间发生因果错配，PBRS 的“策略不变性”反而会提供虚假安全感，策略将把痛点从被测量的区域**位移**到盲区，形成“指标漂亮、部署仍疼”的奖励黑客闭环，故必须以**悲观上界痛点场 + 主动盲区挖掘 + 独立反事实绊线**为硬约束，宁可奖励保守，也不把“痛点场覆盖不到的安静”当作安全。
