# 第 10 轮（新灵感循环第 2 轮；本轮灵感：「步骤分」×「预测性维护」）
> **基线**：第 9 轮 MetricVoiceGauge-ACMD（定义 532–539；引理 82–86；实验 E551–E570）。
> 本轮纪律：**步骤分细化 + 余量预测维护**。v9 把决策分成 K 步块、把退化变成契约，但仍有两个"粗粒度"债：(i) 块证书是单一标量，块内某一步已经劣化而整块仍"合格"；(ii) 契约退化是反应式的，Δ_dom 与 deadline overrun 都晚于真实失效。v10 用"步骤分"把证书细分到步，用"预测性维护"把退化从事后补救变成事前保养；两者共享同一条步骤级遥测流，但必须用独立见证者切断同源自证。

## 0. 直觉与动机

**灵感 1（步骤分 → 非补偿式逐步证书）**
直觉：考试里的"步骤分"不是把总分平均摊给每一步，而是每一步按可验证的规则独立给分；更关键的是，安全相关的步骤不能拿"后续步骤做得好"来补偿。v9 的块证书 Ĉ_t 像只看最终答案：ĝ_min 是块内最坏值，但系统不知道哪一步最坏、坏多少、是否正在变坏。核心创新：**步骤分证书器（StepRubricCertifier, SRC）**：为块内每步 k 生成四元 rubric r_k=(r_k^s, r_k^c, r_k^p, r_k^e)——安全余量、前向一致性、任务进展、能耗；步分 s_k=min(r_k^s, r_k^c) 采用**不可补偿聚合**，块分 S_t=min_k s_k。部分分只用于候选排序、中止点选择、信用归因，绝不允许"用进展换安全"。附带收益：块证书从"是否合格"升级为"每一步的可解释诊断"，直接服务 v9 的 ID 归因。

**灵感 2（预测性维护 → 证书余量的 RUL 与保养）**
直觉：预测性维护不是等机器坏了再修，而是用振动/温度/电流的趋势估计剩余使用寿命（RUL），在下一次停机窗口做保养。v9 的安全余量恰恰是一种"可消耗资源"：前向模型残差、标定漂移、域偏移都在缓慢消耗它；而 MW 的 deadline overrun 与 DA 的 Δ_dom 都是"坏了才报"。核心创新：**预测性维护调度器（PredictiveMaintenanceScheduler, PMS）**：把每步一致性残差 r_k^c 当作证书余量的"磨损遥测"，估计证书余量 M_t 的 RUL `T_cert`，预测模块健康与失效风险 ρ_m，并在**安全维护窗口**（块边界/中止点）执行保养动作（收紧 β̂、缩短 K_eff、重标定、预载权重、切换冗余）。关键是**只允许缩短 K_eff、不放宽安全边界**，且任何非单调动作必须先在中止点终止当前块并重签证书。

**二者的耦合（本轮真正的统一）**
步骤分提供高频、逐步的"磨损信号"；预测性维护把这条信号变成"还剩多少安全余量"的前瞻判断；反过来，维护动作改变模块健康 h_m，而 ID 用步骤级信用 c_m^step 判断模块价值——于是形成**模块生命周期管理**：横轴价值 c_m、纵轴健康 h_m，四个象限分别对应保留/保养/休眠/退役。v9 的"蒸馏"和 v10 的"维护"不再是两套逻辑，而是同一张二维策略表的两列。

## 1. 研究问题（轮次升级版）

- **Q1（步骤分证书的保守性与可比性）**：怎样的 rubric 与不可补偿聚合，能使 v10 的接受集在关闭 SRC 时严格塌缩为 v9 的标量证书？步骤级残差审计能否比 Δ_dom 更早发现"块证书已失效"，且误报可控（ARL0）？
- **Q2（证书余量可预测性）**：在域偏移下，步骤残差是否携带证书余量耗尽的提前信息？预测性 K_eff 门控在什么条件下保证不放大 v9 的风险，而不是用"维护"掩盖模型失配？同源残差与前向模型共模失效如何被独立见证者切断？
- **Q3（维护-蒸馏的生命周期一致性）**：预测性维护与创新蒸馏在什么条件下可以统一为模块生命周期动作而不离开 v9/v8 退化格点？如何防止维护动作造成证书中途失效、维护抖动，以及"把维护收益误记为模块贡献"的双重计数？

## 2. 设计原则（在 P10–P12 基础上新增 P13–P15）

**P13 步骤分不可补偿律（Non-Compensatory Step Rubric, SRC）**
每一步独立评分；安全与一致性维度用 min 聚合，进展/能耗只用于排序与中止点选择，不能补偿安全赤字。块有效 ⇔ `S_t=min_k s_k ≥ τ_step` 且总进展 ≥ τ_prog。Rubric 由独立验证器计算，策略不得直接优化 rubric（防 Goodhart）。

**P14 安全维护不变式（Safe-Maintenance Invariant, PMS）**
维护只在安全维护窗口 W_t（块边界或已证明的中止点）执行；每个动作要么安全单调（缩短 K_eff、增大 d_safe、预载/切冗余），要么先终止当前块、在中止点停驻并在动作后重签证书再恢复。维护永不抢占安全关键步骤（M₀/SpatialCert/FaultCert/AC 守卫）。PMS 失效 ⇒ ρ≡0、无维护，K_eff 严格回到 v9 反应式门控。

**P15 证书余量消耗品律（Certificate-Margin as Consumable, CM）**
定义证书余量 M_t=S_t−τ_step 及其 RUL `T_cert`；步骤一致性残差是 M_t 的磨损遥测。预测门控只允许 `K_eff^PM ≤ K_eff^v9`，且 `K_eff^PM` 由"余量在块结束前耗尽的概率"驱动。维护（β̂ 重标定、前向模型刷新、模块保养）必须像硬件保养一样排程，而不是失效后补救。

## 3. 与基线的接口（如何退化）

- PMS 失效（健康模型不可用/预测超时）⇒ ρ_cert≡0、ρ_m≡0、无维护，K_eff=K_eff^v9，逐位等价 v9 反应式门控；
- SRC 失效 ⇒ 标量块证书（v9 定义 533），步骤 rubric 与残差 CUSUM 关闭，等价 v9 AC；
- SHL（台账）失效 ⇒ 步骤级信用冻结，ID 退回 v9 块级消融（定义 537）；
- v9 的 AC/MW/ID 失效 ⇒ 按 v9 五级链逐级退回 v8/v7；
- 全部失效 ⇒ MetricVoiceGauge-OTL-GC-ER v7 → v6。

## 4. 预期贡献

1. **步骤分证书**：把块证书从"最坏标量"细化为逐步、可解释、不可补偿的 rubric；证明关闭 SRC 时接受集塌缩为 v9，并给出步骤残差 CUSUM 的检测延迟/误报界；
2. **证书余量预测性维护**：把安全余量建模为可消耗资源，用步骤遥测估计 RUL，以预测性 K_eff 门控直接攻击 v9 的"Δ_dom 滞后"最大风险；给出安全维护不变式与单调性引理；
3. **模块生命周期管理**：价值×健康二维策略统一维护与蒸馏，附"维护收益不得计入模块贡献"的反双重计数规则；
4. **可审计闭环**：步骤分健康台账（哈希链）把 rubric、残差、RUL、维护动作与结果串成可复现证据；E571–E592 覆盖保守性、提前检测、RUL 精度、维护安全、抖动、Goodhart/对抗遥测与端到端。

## 5. 本轮最大风险

**一句话**：步骤分残差与证书余量 RUL 都从同一个前向模型 F̂ 派生，陌生域会让它们"一起自信地错"——系统在最该退回 v8 的时刻，反而把失效余量预测成健康、用一次"保养"把危险掩盖过去。

# 第 10 轮产物 · 创新点清单 v10：**MetricVoiceGauge-SRPM**（Metric Voice Gauge with Step-Rubric & Predictive-Maintenance）

> 背景：第 9 轮 MetricVoiceGauge-ACMD（定义 532–539；引理 82–86；实验 E551–E570）。
> 本轮灵感：「步骤分」×「预测性维护」
> **继承纪律**：MetricVoiceGauge 九不变式与 v9 的 AC/MW/ID 三模块原样保留；v10 新增组件一律为**可选增强**：PMS 不可用 ⇒ 关闭预测性门控与维护，严格回到 v9 反应式退化；SRC 不可用 ⇒ 退回 v9 标量块证书；SHL 不可用 ⇒ ID 退回 v9 块级消融。任一新组件失效都必须逐位等价退回 v9，而非行为漂移。

## 1. 符号体系增量（定义 540–551）

| 符号 | 含义 |

| r_k=(r_k^s,r_k^c,r_k^p,r_k^e) | 第 k 步 rubric：安全余量、前向一致性、任务进展、能耗，均 ∈[0,1] |

| R_t=(r_1,…,r_K) | 块 rubric 证书 |
| S_t=min_k s_k, P_t=Σ_k w_k r_k^p | 块最差步分与加权进展 |
| e_k, Z_k, h_c, τ_c | 步骤残差、CUSUM 统计量、报警阈、一致性阈 |
| β_t, β̂_t | 当前证书余量（标量）与在线残差尺度估计 |
| M_t=S_t−τ_step | 证书余量（可消耗资源） |
| T_cert(t), ρ_cert(t) | 证书余量 RUL 与块内耗尽概率 |
| h_m(t), RUL_m(t), ρ_m(t) | 模块健康、剩余使用寿命、失效风险 |
| a=(type,c_a,d_a,φ_a,E_a) | 维护动作：类型、成本、时长、前置条件、效果 |
| W_t | 安全维护窗口（块边界 ∪ 满足停车不变式的中止点） |
| T_maint, ρ_on>ρ_off | 维护冷却期与滞回阈 |
| K_eff^PM(t) | 预测性有效块长（≤K_eff^v9） |
| ℓ_t, H_t | 台账条目与哈希链头 |
| Q_m=(c_m,h_m) | 模块生命周期坐标：价值×健康 |
| c_m^step | 步骤级归因信用（v9 定义 537 的细化） |

**定义 540（步骤分 rubric StepRubric）** 每步 k 输出四元组：
```
r_k^s = clip((ĝ_k − d_safe)/δ_s, 0, 1)          # 安全余量
r_k^c = clip(1 − e_k/β_t, 0, 1)                 # 前向一致性（残差越小分越高）
r_k^p = clip(Δprog_k/Δprog_ref, 0, 1)          # 任务进展
r_k^e = clip(1 − ê_k/τ_eff, 0, 1)               # 能耗/舒适
s_k   = min(r_k^s, r_k^c)                       # 安全步分：不可补偿
```
其中规划期 `e_k` 取前向模型集成方差 `û_k` 作为预测残差代理，执行期改为定义 542 的实测残差；`r_k^p` 与 `r_k^e` 只参与排序，不进入 `s_k`。安全步分采用 min 的理由：安全与一致性是"一票否决"维度，部分分只能决定"退到哪里"，不能决定"是否可以冒险"。

**定义 541（步骤分证书 RubricCertificate）** 长度为 K 的块产生 `R_t=(r_1,…,r_K)`，并定义：
```
S_t = min_{k≤K} s_k
P_t = Σ_{k≤K} w_k r_k^p
R_t 有效 ⇔ S_t ≥ τ_step ∧ P_t ≥ τ_prog
```
塌缩算子 `col(R_t) = (min_k ĝ_k − β_t, max_k ê_k + β_t, ∧_k γ̂_k)` 把逐步 rubric 还原为 v9 标量块证书的三元组；当 `S_t ≥ τ_step` 时 `col(R_t)` 必满足 v9 定义 533 的证书条件（引理 87）。

**定义 542（步骤残差审计与 CUSUM StepResidualAudit）** 执行第 k 步后观测 `y_k`，预测 `ŷ_k`：
```
e_k = ||y_k − ŷ_k|| / σ_y
Z_k = max(0, Z_{k−1} + (τ_c − r_k^c)),  Z_0=0
alarm_k ⇔ Z_k > h_c
β̂_{t+1} = 1.2 · Quantile_{1−α}({e_j}_{j∈W_t})
```
`Z_k` 对"一致性分数持续低于 τ_c"累积证据；报警即触发步骤级中止或 PMS 维护评估。`β̂` 是残差尺度的在线估计，维护时用它更新 `β_t`（定义 547）。

**定义 543（证书余量与 RUL CertificateMargin）**
```
M_t = S_t − τ_step ∈ [0, 1−τ_step]
\dot M_t = EWMA((M_{t−1} − M_t)/Δt)             # 余量消耗速率
T_cert(t) = inf{Δ≥0 : M_t − \dot M_t·Δ < 0}     # 若 \dot M_t≤0 则为 +∞
ρ_cert(t) = P(T_cert(t) ≤ K_eff^v9(t)·Δt | ℓ_{≤t})
```
`M_t` 是"还能承受多少步劣化"的预算；`ρ_cert` 是"这个块还没跑完余量就耗尽"的概率。

**定义 544（模块健康与风险 ModuleHealth）** 模块 m 的健康 `h_m(t)∈[0,1]`，遥测
```
x_m(t) = (deadline_slack, residual_trend, calib_drift, temperature, SNR, battery)
h_m(t+1) = h_m(t) − η_m(x_m(t)) + ξ_t
RUL_m(t) = inf{Δ≥0 : P(h_m(t+Δ) ≤ h_fail | x_{≤t}) ≥ 1−α}
ρ_m(t) = P(RUL_m(t) ≤ H_m)
```
`η_m` 为退化速率（Weibull/贝叶斯在线更新均可）；`ρ_m` 是维护决策的输入，不是安全证书的替代品。

**定义 545（维护动作与安全窗口 MaintenanceAction）**
```
a = (type, c_a, d_a, φ_a, E_a)
W_t = ∂chunk ∪ {p ∈ P_t : d_stop(p) ∧ (K−p)·Δt ≥ d_a}
```
维护动作表：

| 动作 | 语义 | 单调性 |
|---|---|---|
| preload weights | 降低 Ŵ_m，不改输出 | 安全单调（只增余量） |
| priority bump | 提前调度，不改输出 | 安全单调 |
| shrink K_eff | 缩短块长 | 安全单调（余量↑、暴露↓） |
| switch redundant | 切到 v^⊥ 等价冗余模块 | 语义恒等（须验证） |
| recalibrate sensor | 改状态估计 | **非单调**，仅安全停驻后 |
| refresh F̂/β̂ | 改前向模型/证书余量 | **非单调**，仅安全停驻后 |
| safe-stop calibration | 在 p* 停驻后标定 | **非单调**，先终止块 |

**定义 546（安全维护不变式 Safe-Maintenance Invariant）** 对任意执行的动作 a：
```
t ∈ W_t ∧ [ mono(a) ∨ (当前块在 p* 中止 ∧ 动作后重签证书再恢复) ]
```
且任何动作不得增大 K_eff、不得减小 d_safe、不得抢占 M₀/SpatialCert/FaultCert/AC 守卫。`mono(a)` 指动作只可能增大安全余量或保持输出语义不变。

**定义 547（预测性维护策略 PredictiveMaintenancePolicy）**
```
若 ρ_m(t) ≥ ρ_on 且 t − last_m ≥ T_maint 且 E[L_avoided(a)] − λ c_a > 0：
    a* = argmax_{a∈A_m, W_t 开放} (E[L_avoided(a)] − λ c_a)
    若 W_t 开放：执行 a*，last_m ← t；否则入队等待最近安全窗口
若 ρ_m(t) < ρ_off：复位滞回与队列
```
维护收益按期望损失避免量计，`λ` 是维护成本权重；`ρ_on>ρ_off` 与 `T_maint` 共同防抖（引理 91）。

**定义 548（预测性块长门控 PredictiveChunkGate）**
```
K_eff^v9(t) = v9 定义 539
K_eff^PM(t) = max(1, floor(K_eff^v9(t)·(1 − max(ρ_cert(t), max_m ρ_m(t)))))
```
PMS 关闭时 `ρ_cert≡0、ρ_m≡0`，故 `K_eff^PM=K_eff^v9`，逐位回到 v9。门控只允许缩短，不允许放大（引理 90）。

**定义 549（步骤分健康台账 StepHealthLedger）**
```
ℓ_t = (t, {r_k}, e_k, Z_k, β_t, M_t, T_cert, {h_m,ρ_m}, a_t, outcome_t)
H_t = Hash(H_{t−1} ‖ ℓ_t),  H_0 = genesis
```
在线用环形缓冲（默认 30k 条 ≈10min@50Hz），周期性写 Merkle 根；`outcome_t` 记录下一步真实观测与守卫判决，供离线校准 RUL 与 β。

**定义 550（模块生命周期表 ModuleLifecycle）** 以 `Q_m=(c_m,h_m)` 分四象限：
```
φ^elig=false：keep；若 h_m<h_low 则 maintain（永不 dormant）
c_m≥c_hi, h_m≥h_low：keep
c_m≥c_hi, h_m<h_low：maintain（高价值低健康，维护优先）
c_m<c_lo, h_m≥h_low：dormant（低价值高健康，蒸馏休眠）
c_m<c_lo, h_m<h_low：dormant + defer maintenance（低价值低健康，预测性退役）
```
其中 `c_lo<c_hi` 为价值滞回，`h_low` 为健康阈；休眠行为严格等于注入 v^⊥（引理 84/92）。

**定义 551（步骤级信用 StepCredit）**
```
c_m^step(t) = EMA_{k∈K_sample} norm(J_with(k) − J_without(k))
c_m(t) = (1−α)c_m(t−1) + α c_m^step(t)
```
`K_sample` 按 rubric 分位分层抽样，避免只在高分步上估计；`J_without` 必须在**相同维护状态**下测量。若某段 ΔJ 可归因于维护动作 a，则记入维护收益 `g_a` 并从 `c_m` 更新中扣除（反双重计数规则）。

## 2. 形式化定义（要点与升级）

**定义 493（六层指标层级）** 继承 v8/v9 不变。
**定义 495/524（MetaWeight/情感，5 维）** 继承不变；步骤 rubric 的 `r_k^p` 取任务进展，不替代情感层。
**定义 521（DA-OTL）** 继承不变；`τ_i(t)` 在 K_eff>1 时由 rubric 逐步复核（v9 块证书是其 min 塌缩）。
**升级定义 496（软证书，v10）** 触发条件扩展为：
```
δ_trigger = {σ < τ_safe ∧ γ_grasp valid ∧ Δ_dom < τ_dom
             ∧ risk_SLAM < τ_SLAM ∧ Ĉ_t valid
             ∧ S_t ≥ τ_step ∧ Z_k ≤ h_c}
```
前五条与 v9 同尺度；后两条把"块内某步已劣化"和"残差已持续偏移"纳入同一触发平面，消除"块平均合格、单步失效"的空洞。
**升级定义 531（软硬约束衔接，v10）** M₀ 增加步骤级入口：
```
r_k^s < τ_abort ∨ r_k^c < τ_abort ⇒ 立即在 p* 中止或安全停驻，不等块边界
```
`τ_abort ≥ τ_step` 可选（先警告后中止），但不得低于证书有效阈。
**升级定义 533（块证书，v10）** `Ĉ_t` 由 `col(R_t)` 生成；SRC 关闭时 `col` 退化为 v9 原始定义，保持逐位一致。
**升级定义 537/538（归因/状态机，v10）** 归因改为定义 551 的步骤级信用；状态机与定义 550 的生命周期表联动：`dormant` 由低价值触发，`maintain` 由低健康触发，两者可同时发生（先维护、再评估是否休眠）。
**升级定义 539（有效块长，v10）** v9 公式作为 `K_eff^v9`，最终执行 `K_eff^PM`（定义 548）。

# IP-357 StepRubricCertifier：步骤分证书器
@dataclass
class Rubric:
    k: int
    safety: float; consistency: float; progress: float; effort: float

class StepRubricCertifier(ActionChunkCertifier):
    def __init__(self, forward_model, policy, K_max=10, beta=0.02,
                 d_safe=0.15, delta_s=0.3, tau_step=0.6, tau_prog=0.3,
                 tau_c=0.7, tau_abort=0.45, h_c=5.0, sigma_y=1.0):
        super().__init__(forward_model, policy, K_max, beta, d_safe)
        self.delta_s, self.tau_step, self.tau_prog = delta_s, tau_step, tau_prog
        self.tau_c, self.tau_abort, self.h_c = tau_c, tau_abort, h_c
        self.sigma_y, self.Z = sigma_y, 0.0

    def step_score(self, r):
        return min(r.safety, r.consistency)          # 定义 540：不可补偿

    def rubric(self, k, pred_k, obs_k=None, mode='plan'):
        r_s = clip((pred_k.clearance - self.d_safe) / self.delta_s, 0, 1)
        if mode == 'plan':
            e_k = pred_k.uncertainty                  # 规划期：不确定性代理
        else:
            e_k = norm(obs_k.y - pred_k.y_hat) / self.sigma_y   # 执行期：实测残差
        r_c = clip(1 - e_k / self.beta, 0, 1)
        r_p = clip(pred_k.progress / self.prog_ref, 0, 1)
        r_e = clip(1 - pred_k.effort / self.tau_eff, 0, 1)
        return Rubric(k, r_s, r_c, r_p, r_e), e_k

    def certify(self, state, K, obs=None):
        best = None
        for cand in self.policy.sample_sequences(state, K, n=64):
            pred = self.F.rollout(state, cand)
            rubrics = [self.rubric(k, pred[k], mode='plan')[0] for k in range(K)]
            S = min(self.step_score(r) for r in rubrics)
            P = sum(self.w[k] * r.progress for k, r in enumerate(rubrics))
            if S < self.tau_step or P < self.tau_prog:
                continue
            pts = self._abort_points_weighted(state, cand, pred, rubrics)
            if not pts:
                continue
            score = (S, P, self.policy.score(cand, pred))
            if best is None or score > best.score_tuple:
                best = Chunk(cand, RubricCert(rubrics, S, P), pts, score)
        return best or self._single_step_fallback(state)

    def _abort_points_weighted(self, state, actions, pred, rubrics):
        # 定义 534 + 部分分：优先选安全步分高的中止点
        cand = []
        for p in range(1, len(actions)):
            remaining = pred.path_len[p:]
            margin = pred.clearance[p] - self.d_brake(pred.speed[p]) - self.d_safe
            if margin >= remaining:
                cand.append((rubrics[p].safety, p))
        return [p for _, p in sorted(cand, reverse=True)]

    def midchunk_guard(self, chunk, k_exec, live_obs):
        # 1) v9 廉价守卫（证书失效 + 停车不变式）
        if not chunk.cert_still_valid(live_obs):
            return ('abort', self._nearest_abort(chunk, k_exec))
        stop_inv = (live_obs.nearest_clearance
                    - self.d_brake(live_obs.speed) - self.d_safe)
        if stop_inv < chunk.remaining_len(k_exec):
            return ('abort', self._nearest_abort(chunk, k_exec))
        # 2) 步骤残差审计（定义 542）
        r_obs, e_k = self.rubric(k_exec, chunk.pred[k_exec], live_obs, mode='exec')
        self.Z = max(0.0, self.Z + (self.tau_c - r_obs.consistency))
        if self.Z > self.h_c or r_obs.safety < self.tau_abort:
            return ('abort', self._best_abort(chunk, k_exec))
        return ('continue', k_exec + 1)


# IP-358 PredictiveMaintenanceScheduler：预测性维护调度器
class PredictiveMaintenanceScheduler:
    def __init__(self, ledger, horizon=50, rho_on=0.7, rho_off=0.4,
                 T_maint=250, lam=1.0, sigma_cert=0.25):
        self.ledger, self.horizon = ledger, horizon
        self.rho_on, self.rho_off = rho_on, rho_off
        self.T_maint, self.lam, self.sigma_cert = T_maint, lam, sigma_cert
        self.last, self.queue, self.models = {}, {}, {}

    def certificate_rul(self):
        M = self.ledger.margin_series(window=200)
        dM = ewma_diff(M)                            # 定义 543
        return float('inf') if dM <= 1e-9 else M[-1] / dM

    def rho_cert(self, K_v9, dt):
        T = self.certificate_rul()
        if T == float('inf'):
            return 0.0
        return lognormal_cdf(K_v9 * dt, median=T, sigma=self.sigma_cert)

    def health(self, m, telemetry):
        h, rul, rho = self.models[m].predict(telemetry)   # 定义 544
        return h, rul, rho

    def predictive_K(self, K_v9, rho_cert, rho_mod):
        return max(1, int(K_v9 * (1 - max(rho_cert, rho_mod))))   # 定义 548

    def plan(self, t, ctx, safe_window):
        actions = []
        for m in self.models:
            h, rul, rho = self.health(m, ctx.telemetry[m])
            if rho >= self.rho_on and t - self.last.get(m, -10**9) >= self.T_maint:
                a = self.choose_action(m, rho, ctx)      # 最小成本且满足定义 546
                if safe_window.is_open(t, a):
                    self.apply(a); self.last[m] = t
                    actions.append(a)
                else:
                    self.queue[m] = a                    # 等到最近安全窗口
            elif rho < self.rho_off:
                self.queue.pop(m, None)
        return actions


# IP-356 InnovationDistiller v10：步骤级信用 + 生命周期
class InnovationDistillerV10(InnovationDistiller):
    def __init__(self, mw, ledger, c_hi=0.05, c_lo=0.01,
                 h_low=0.4, alpha=0.1, **kw):
        super().__init__(mw, **kw)
        self.ledger, self.c_hi, self.c_lo = ledger, c_hi, c_lo
        self.h_low, self.alpha = h_low, alpha

    def attribute_stepwise(self, module, window):
        samples = stratified_by_rubric(window, n=32)    # 定义 551
        deltas = []
        for k in samples:
            J_with = replay_with_module(module, k)
            J_without = replay_without_module(module, k)  # 同维护状态
            deltas.append(normalize(J_with - J_without))
        return median(deltas)

    def lifecycle(self, m, c_m, h_m, eligible):
        if not eligible:
            return 'maintain' if h_m < self.h_low else 'keep'
        if c_m >= self.c_hi:
            return 'maintain' if h_m < self.h_low else 'keep'
        if c_m < self.c_lo:
            return 'dormant'                              # 低价值 → 蒸馏
        return 'keep'

    def step(self, cycle_idx, ctx, ledger=None):
        if ctx.delta_dom >= ctx.tau_dom:
            self.wake_all(); return
        if cycle_idx % self.T_abl == 0:
            for m in self.eligible_modules():
                c_step = self.attribute_stepwise(m, ledger.window(self.abl_len))
                self.ema[m] = (1 - self.alpha) * self.ema.get(m, c_step) + self.alpha * c_step
        for m, c in self.ema.items():
            h = ctx.health[m]
            action = self.lifecycle(m, c, h, self.is_eligible(m))
            if action == 'dormant' and self.state[m] == 'active':
                self.state[m] = 'dormant'; self.mw.set_dormant(m)
            elif action == 'maintain':
                self.pms.enqueue(m)                       # 维护优先，不立即休眠
            elif action == 'keep' and self.state[m] == 'dormant':
                self.state[m] = 'active'; self.mw.set_active(m)

## 4. 推导

**引理 87（rubric 塌缩与 v9 保守性）** 设同一前向模型 F̂、同一证书余量 `β_t≥β`，且 `τ_step` 不低于 v9 三项谓词的归一化阈。则：(i) 任意 v10 接受块 ζ 满足 v9 标量块证书 `Ĉ_t`（定义 533）；(ii) 若 SRC 关闭、rubric 退化为 v9 谓词的 0/1 指示，则 v10 接受集与 v9 接受集逐块相同。证明：由定义 540–541，`S_t≥τ_step` 蕴含每步 `r_k^s≥τ_step`、`r_k^c≥τ_step`，即每步预测间隙不低于 `d_safe`、残差不超 `β_t`；取块内 min/max 即得 `col(R_t)` 的 `ĝ_min≥d_safe`、`ê_max≤τ_eff`，故 (i) 成立。(ii) 令 rubric 三安全项等于 v9 三谓词，min 与 v9 的块内最坏值重合，`col(R_t)=Ĉ_t`；进度项取常数 1 时 `P_t≥τ_prog` 恒真，故接受判据逐块重合。∎

**引理 88（步骤残差 CUSUM 的误报与延迟界）** 设域内每步 `r_k^c` 独立同分布、均值 `μ_0>τ_c`（记 `δ_0=μ_0−τ_c`），域偏移后均值 `μ_1<τ_c`（记 `δ_1=τ_c−μ_1`），且 `r_k^c∈[0,1]`。令 `g_k=τ_c−r_k^c`、`Z_k=max(0,Z_{k−1}+g_k)`，报警阈 `h_c`。则：(i) 域内到时刻 n 的误报概率 `P(alarm by n) ≤ n·exp(−(h_c+nδ_0)^2/(2n))`；(ii) 偏移后期望检测延迟 `E[delay] ≤ 2h_c/δ_1 + 1`，且 `P(delay>2h_c/δ_1) ≤ exp(−h_cδ_1/4)`。证明：对 `g_k` 用 Hoeffding 有界不等式；域内 `E[g]=−δ_0`，偏移后 `E[g]=δ_1`，分别代入阈值 `h_c` 与 `n=2h_c/δ_1` 即得。∎
> **注 1（相关性修正）** 真实残差在域偏移下相关，独立性假设偏乐观；部署时用块自助法（block bootstrap）在 SHL 域内数据上标定 `h_c`，并把引理 88 作为"独立近似段"的上界，而非全局保证。

**引理 89（安全维护不变式）** 若所有维护动作满足定义 546，则当前执行块在每一步仍满足停车不变式；维护不会在块内制造新的不安全状态。证明：对已执行步数归纳。单调动作只增大安全余量或保持输出语义（preload/priority/shrink K/switch redundant），故定义 534 的不变式保持；非单调动作（recalibrate/refresh/β̂ 更新）要求先在中止点 `p*` 终止当前块并重签证书，恢复时从新证书的 `P_t` 重新开始，故不存在"旧证书 + 新状态"的混合。安全关键模块不被维护抢占，M₀/SpatialCert/FaultCert 的硬检查仍每周期执行。∎

**引理 90（预测性门控的单调安全性）** 设 v9 接受块 ζ 长度为 K，其中止点集为 `P_t`；v10 只做前缀截断 `ζ'=ζ_{1:K'}`，`K'=K_eff^PM≤K`，且若 `K'<min P_t` 则回退 `K'=1`（v8 逐步）。则：(i) 若 `K'≥min P_t`，`P'_t={p∈P_t: p≤K'}` 非空且每个 `p` 仍满足停车不变式；(ii) 任意 `K'≤K` 的截断只减少暴露步数，不增加所需刹停距离。故 v9 引理 82 的中止安全性对 v10 成立。证明：(i) 对 `p∈P'_t`，原不变式 `d_brake(v_p)+d_safe ≤ dist(s_p,O)−|traj_{p:K}|`；截断后剩余轨迹 `|traj_{p:K'}|≤|traj_{p:K}|`，右侧不减，故仍成立。(ii) 由 (i) 与前缀定义直接得。∎
> **设计约束**：PMS 只允许对已由 v9 证书接受的块做前缀截断，不允许用预测模型重新生成更长的块；这是引理 90 成立的前提。

**引理 91（维护无抖振 / 有界动作数）** 在 `ρ_on>ρ_off`、冷却期 `T_maint`、动作集有限 `|A|` 下，任意长度 T 的区间内维护动作数 `N(T) ≤ |M|·(⌈T/T_maint⌉+1)`；维护状态翻转间隔至少 `T_maint`，无 Zeno 行为。证明：每模块每次动作后 `last_m` 更新并至少等待 `T_maint`；滞回保证 `ρ` 在 `[ρ_off,ρ_on)` 内不触发新动作；有限动作集给出计数上界。∎

**引理 92（生命周期一致性 / 不离开安全格点）** 在定义 550 的策略下，任意模块状态迁移对应以下之一：(i) keep/maintain——不改变模块输出语义，只改调度/资源，行为仍在 v9 可达集；(ii) dormant——等价于注入 `v^⊥`，由 v9 引理 84 属于 v8 退化格点；(iii) retire——dormant + 推迟维护，仍为 `v^⊥`；(iv) 非单调维护——按定义 546 在安全停驻后重签证书。`φ^elig=false` 的安全关键模块永不 dormant。故任意生命周期轨迹的系统行为 ⊆ v9 退化格点 ∪ 安全重签证书，安全性由 v9 引理 80–84 传递。∎

**引理 93（独立见证下的共模逃逸界）** 令 E 为"F̂ 派生的 rubric 与 PMS 都判健康、但真实证书已失效"的事件。若存在独立见证 W（M₀ 几何硬检查、SpatialCert 或物理不变式），其假阴性率 `ε_W`，且 W 与 F̂ 在给定失效状态下条件独立，则 `P(E) ≤ ε_W + P(W 不可用)`。证明：E 发生意味着 W 未报警或不可用；由条件独立与假阴性率，`P(E) ≤ P(W 漏报) + P(W 不可用) ≤ ε_W + P(W 不可用)`。∎
> **注 2（无独立性则无界）** 若 W 与 F̂ 共享传感器或特征，则条件独立不成立，共模失效无法被界住。这正是 v10 强制保留 M₀/SpatialCert/FaultCert 为 `φ^elig=false`、且 PMS 的非单调动作必须经过它们复核的原因；也是本轮最大风险的来源。
