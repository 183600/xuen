# 第 47 轮（承接第 46 轮 v23；本轮灵感：用户需求分析 × 单模型多任务） · Need-MultiTask-Cert：需求契约驱动的单模型多任务证书与需求可满足性协商（五层架构 v11）

> 承接第 46 轮产物 v23（MVR × VAD × SAB 记忆-语音-安全闭环）。v23 把「用户说了什么」做成语音槽位分布、把历史决策做成可检索记忆，但压着两条隐含假设：**H5**「用户需求 = 显式语音指令，且优先级/质量/时延容忍度已知」——真实需求常是欠指定、多维、彼此冲突（快 vs 稳 vs 省 vs 准），一句话根本没说全；**H6**「各能力由独立专用模型承担，算力/能耗可加、错误相互独立」——实机上 ASR、VLM 上下文、姿态头、深度质量、记忆编码、安全绑定若各自一个模型，切换与显存开销爆炸，第 45 轮的能量租约被直接吞噬。本轮灵感精确命中：**用户需求分析**迫使我们把「需求」从一条指令升级为带共形覆盖的**需求集 + 接受谓词**，先证「需求可满足」再执行；**单模型多任务**给出把模型动物园收敛为**共享主干 + 任务头**的路径，省算力省能量，却把原本独立的错误变成**相关错误与任务干扰**。二者耦合处是真正的新问题：**共享主干让任务误差相关，需求集又让目标本身不确定，于是「逐任务独立校准的证书」在联合执行时不再 sound——系统可能证明「需求已满足」却在优化错误的任务，或在能量/干扰下静默违反质量与安全**。

## 0. 直觉与动机

**灵感 1（用户需求分析 → 需求是带覆盖集的不确定性，而非一条指令）**
直觉：用户说“把它拿稳一点”，其实同时表达了目标、质量下限、时延容忍与安全级别，但每一维都只说了一部分；断言式解析会把不确定性抹平。正确做法是把需求表示为后验上的一个**共形集** Ĝ_t（以 1-α_n 覆盖真实需求），并在整个集合上要求满足，而不是对点估计优化——这样“需求分析错了”不再是安全隐患，而会体现为**集合变大 → 可满足性变难 → 触发协商**。

**灵感 2（单模型多任务 → 共享主干把独立误差变成相关误差）**
直觉：一个共享视觉-语言主干 + 若干任务头（ASR/上下文/姿态/深度质量/记忆嵌入/安全绑定/需求推断），比 7 个独立模型省 3–5× 显存与切换能耗，直接抬高能量租约。但共享特征意味着任务 i 的错误不再是独立事件：一个被遮挡样本可能同时让姿态头与深度质量头一起错；联合推断时还会互相干扰（干扰矩阵 I_ij）。因此逐任务用各自校准集算出的共形半径 r_i 在“多任务同批执行”分布下会系统性偏小，联合覆盖率失效。

**灵感 3（耦合 → 需求可满足性证书 RSC 与协商闭环）**
直觉：与其“尽力而为”地执行一条模糊指令，不如先回答一个可验证的问题：**在整条需求集 Ĝ_t、当前多任务证书与能量租约下，是否存在一条策略能同时满足所有接受谓词？** 能，则签发 RSC 并执行；不能，则进入**协商**（向用户提供若干可行选项、请求澄清、或明确降级并告知），绝不静默降级。这把“需求分析”从提示工程变成证书的前置条件。

**耦合升级（五层 v11）**：在 v23 的四层/记忆-语音闭环上新增 **需求-多任务证书层**。NCA 产出需求集 Ĝ_t 与接受谓词；SMM 把各任务统一为一个共享主干并输出干扰矩阵 I；RSC 在 (Ĝ_t, 共享证书, ℓ_e, δ_t) 上做鲁棒可满足性判定；MVR/VAD/SAB 全部改为对 Ĝ_t 而非单点需求工作；CAR 增加「可满足性 + 干扰界」守卫；DCL 采集「需求误判样本 + 高干扰样本」。五层 v11：根信任层加需求覆盖租约 ℓ_n；L1 需求层；L2 共享主干与任务路由层；L3 证书层（任务条件共形 + 干扰膨胀）；L4 协商/安全层。

## 1. 形式化定义（增量：定义 59–63）

**定义 59（需求轮廓与需求契约）**
需求轮廓 n_t=(g_t, p_t, δ_t, ε_t, κ_t)：目标分布 g_t∈Δ(G)、优先级向量 p_t、时延预算 δ_t、质量接受阈 ε_t、安全等级 κ_t∈{S0,S1,S2}，以及偏好约束集 F_t。需求契约 N_t=(Ĝ_t, ε_t, δ_t, κ_t)，其中 Ĝ_t 为以 1-α_n 覆盖真实需求 n_t 的共形集：
P(n_t ∈ Ĝ_t) ≥ 1-α_n。

**定义 60（需求→任务与接受谓词）**
任务库 T={τ}，映射 m:G→2^T。接受谓词 A_τ(y; ε, δ, κ)∈{0,1} 表示任务 τ 的输出 y 在质量阈 ε、时延 δ、安全级 κ 下可接受。需求满足事件
Sat(N_t)=∧_{τ∈m(g_t)} A_τ(y_τ; ε_t, δ_t, κ_t)。
**鲁棒满足**要求对 Ĝ_t 中所有 g 的服务集 m(g) 仍可被同一策略覆盖。

**定义 61（单模型多任务干扰矩阵与相关风险）**
共享主干 f_θ + 任务头 {h_i}。任务干扰
I_ij = E[err_i(f,h_i | 同批执行含 j)] − E[err_i(f,h_i | 单独执行)]；
误差相关 ρ_ij = Corr(1[err_i>q_i], 1[err_j>q_j])。多任务联合失败风险不再等于 ∏(1−α_i)，一阶界
P(∪_i fail_i) ≤ Σ_i α_i − Σ_{i<j} max(0,ρ_ij)·√(α_iα_j)·c_ρ。
正相关会破坏“独立”假设下紧致性、负相关/干扰项 I_ij 需显式膨胀；上界必须用实测 (I,ρ) 而非名义 α。

**定义 62（任务条件共形 + 干扰膨胀的共享主干证书）**
对任务 i 在共享特征上按任务条件校准非一致性分数 s_i(x,y) 与得分位 q_i。共享主干证书 C_i=(q_i, I_·i, ρ_·i)，半径
r_i^MT = r_i^ST + L_I·Σ_{j∈B} w_j I_ij + L_ρ·Σ_{j∈B} |ρ_ij|·r_j^ST。
**多任务 soundness**：对任意同批任务集 B，
P(A_i=1 | C_i^MT, B) ≥ 1−α_i，
且额外项显式吸收串行定标与同批执行分布之间的差距。

**定义 63（需求可满足性证书 RSC 与协商集）**
给定 Ĝ_t、共享证书 {C_i^MT}、能量租约 ℓ_e、时延预算 δ_t，
RSC_t = P( Sat(N_t) | Ĝ_t, {C_i^MT}, ℓ_e, δ_t )。
若 RSC_t ≥ 1−β 且存在可行任务子集 B⊆m(Ĝ_t) 同时满足能量与时延，则签发执行；否则输出协商集
Neg_t = { (B, RSC_t(B), Δquality, Δlatency) : B 能量/时延可行 }，
按“距用户优先级 p_t 的加权偏离”排序返回。**协商不变式**：绝不把不可满足需求静默当作可满足执行（fail-open 禁止）。

## 2. 三大新增产出与既有 IP 升级

**IP-69 NCA（Need-Cert Analyzer，需求分析器）**
- 多维需求推断：从语音槽位 + 视线/最近任务 + 操作历史 + 上下文，输出 (Ĝ_t, p_t, δ_t, ε_t, κ_t)
- 需求共形集：用独立审计集校准 Ĝ_t 覆盖率 1−α_n；覆盖不足则扩大集合
- 需求冲突检测：快/稳/省/准冲突时生成 Pareto 协商候选，而非简单平均化
- 欠指定触发主动澄清（复用 IP-67 语言交互）

**IP-70 SMM（Single-Model Multi-Task 共享主干）**
- 统一主干 + 任务头 + 任务 token/LoRA 路由：ASR/上下文/姿态/深度质量/记忆嵌入/安全绑定/需求推断共用编码
- 干扰矩阵在线估计：按任务对采样，维护 I_ij、ρ_ij，供 IP-71 膨胀半径
- 能量感知任务批调度：共享主干一次前向服务多任务，替代串行多模型，降低 P_m 与切换能耗
- 相关失效哨兵：共享特征置信骤降时同时冻结所有依赖头（防“一个遮挡骗过全部任务”）

**IP-71 RSC（Requirement Satisfiability Certificate & Negotiator）**
- 鲁棒可满足性判定：在 Ĝ_t 上做最坏情况/分布鲁棒覆盖判定
- 能量-时延-质量联合可行域搜索：小规模任务子集枚举 + 剪枝
- 协商生成与排序：按用户优先级 p_t 的加权偏离给出可选项
- 不可满足时 fail-closed 或显式降级（调用 IP-68 安全队列）

**既有 IP 升级**
IP-66 MVR：记忆键加入需求契约 N_t；命中还需 RSC 复核，历史“成功但需求不同”不直接复用
IP-67 VAD：槽位解析接入 NCA，欠指定指令转主动澄清而非猜测
IP-68 SAB：安全绑定阈值随 κ_t 自适应；协商中的选项也必须过 B(v,P) 检查
IP-63 ECPS：能量预算按共享主干单次前向分配，模态决策附带任务批 B_t
IP-61 DCL：新增“需求误判样本”“高干扰样本”两类采集任务
IP-62 CCA：新增需求集覆盖红队、多任务相关失效注入、协商可用性测试
IP-51 CAR：守卫新增 RSC_t≥1−β 与干扰界 I_ij≤I_max
IP-45 总线：新增 need-contract / multitask-batch / interference-estimate / negotiation 话题

## 3. 算法骨架

每控制周期：
1. NCA 读多模输入，输出 Ĝ_t、p_t、δ_t、ε_t、κ_t
2. SMM 维护 I_ij、ρ_ij，按定义 62 算各任务 r_i^MT
3. 枚举候选任务批 B⊆m(Ĝ_t)，查能量 ℓ_e 与时延 δ_t 可行性
4. 对每个可行 B 计算 RSC_t(B)（定义 63）
5. 若 ∃B: RSC_t(B)≥1−β → 执行该 B 并签发联合证书 J_t=(P_t, ℓ_p, ℓ_e, ℓ_n, C^MT, B)
6. 否则生成并返回协商集 Neg_t（按 p_t 加权偏离排序），或 fail-closed
7. 任一环覆盖率不达标（需求/任务）→ 扩大集合重估；仍不行则降级并显式告知

## 4. 本轮最大风险

**一句话**：单模型多任务把各能力压进共享表示、需求集 Ĝ_t 又把“目标”变成不确定集合，二者叠加会让 RSC 在“看起来可满足”时其实优化了错误任务或低估了跨任务相关失效——证书 soundness 被悄悄破坏；因此必须在真实同批执行分布上校准干扰矩阵与相关性、对 Ĝ_t 做独立覆盖审计，并在任一项无法认证时直接进入协商或 fail-closed，而不是信任逐任务独立校准。

## 2. 关键算法 伪代码

### IP-69 NCA：需求集与契约
```python
def need_analyze(voice, gaze, history, ctx, audit, alpha_n=0.05):
    z = smm_backbone(voice, gaze, history, ctx)      # 共享主干一次前向
    g_hat = softmax(task_head_goal(z))
    p_hat = priority_head(z)                         # 各维优先级
    delta_hat, eps_hat = budget_head(z)              # 时延/质量预算
    kappa_hat = argmax(safety_head(z))               # S0/S1/S2
    # 需求共形集：审计集校准非一致性分数
    s_audit = [need_score(n, z) for n in audit]
    q_n = quantile(s_audit, 1 - alpha_n)
    G_hat = [n for n in keep_promising(g_hat) if need_score(n, z) <= q_n]
    if need_conflict(G_hat, F=prefs(z)):            # 快/稳/省/准冲突
        return NeedContract(G_hat, p_hat, delta_hat, eps_hat, kappa_hat), conflict=True
    return NeedContract(G_hat, p_hat, delta_hat, eps_hat, kappa_hat), conflict=False
```

### IP-70 SMM：干扰矩阵与膨胀半径
```python
def update_interference(T, err_alone, err_batch, succ, window):
    for i in T:
        for j in T:
            if i == j: continue
            I[i][j]   = ema(I[i][j],   err_batch[i][j] - err_alone[i], window)
            rho[i][j] = ema_abs_corr(rho[i][j], succ[i], succ[j], window)
    return I, rho

def mt_radius(i, B, r_st, I, rho, L_I=1.0, L_rho=1.0, w=1.0):
    inflate = L_I * sum(w * I[i][j]   for j in B if j != i)
    corr    = L_rho * sum(abs(rho[i][j]) * r_st[j] for j in B if j != i)
    return r_st[i] + inflate + corr

def mt_certificate(B, r_st, I, rho):
    return {i: (q_i, mt_radius(i, B, r_st, I, rho)) for i in B}
```

### IP-71 RSC：鲁棒可满足性与协商
```python
def rsc(N, certs, energy_lease, delta, beta=0.01):
    best_neg = None
    for B in feasible_batches(N.task_set, energy_lease, delta):
        cB = mt_certificate(B, certs.r_st, I, rho)
        # 在需求集最坏点上评估满足概率
        p_sat = min(coverage_sat(g, B, cB) for g in N.G_hat)
        if p_sat >= 1 - beta:
            return True, B, cB, p_sat, None
        cand = (B, p_sat, quality_delta(B, N.eps), latency_delta(B, N.delta))
        best_neg = better_by_priority(best_neg, cand, N.p)
    return False, None, None, None, best_neg

def negotiate(N, neg):
    if neg is None:
        return 'fail-closed'                 # 无任何可行选项
    return sorted_options_by(N.p, neg)       # 返回用户选择/澄清
```

### 全局决策 Π_v11

def global_decision_v11(ctx, omega, B_bat, voice, M, Q_safe):
    N, conflict = need_analyze(voice, gaze, history, ctx, audit)
    if conflict:
        return 'clarify', clarify_options(N)      # 主动澄清优先
    # 记忆仅作候选，必须 RSC 复核
    mem = mvr_lookup(voice, N, ctx, M)
    ok, B_tasks, cB, p_sat, neg = rsc(N, shared_certs, B_bat, N.delta)
    if not ok:
        return ('negotiate', negotiate(N, neg))
    result = smm_execute(B_tasks)                  # 共享主干一次前向
    B_prob = safety_bind(voice, pose_certify(result), omega, kappa=N.kappa)
    if B_prob < theta_safe(N.kappa):
        push(Q_safe, voice, N)
        return ('queued', result, B_prob)
    J = joint_cert(pose=pose_certify(result), lease_p=lp, lease_e=B_bat,
                   lease_n=N, certs=cB, batch=B_tasks)
    return ('execute', result, J, 'memory' if mem else 'realtime')

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| NCA 需求分析 | O(d_backbone+\|G\|) | O(\|G\|) | 审计集校准 ⇒ P(n_t∈Ĝ_t)≥1−α_n |
| SMM 干扰更新 | O(\|T\|²) 每次采样 | O(\|T\|²) | 实测 (I,ρ) 进入半径 ⇒ 联合覆盖率不虚高 |
| SMM 单次前向 | O(C_shared+ΣC_head) | O(d_shared) | 共享主干替代多模型 ⇒ 能耗/切换下降 |
| RSC 可满足性 | O(2^{\|m(G)\|})（剪枝后 O(\|T\|·\|B\|)） | O(\|B\|) | 需求集最坏点评估 ⇒ 鲁棒满足 |
| 全局决策 Π_v11 | O(RSC) | O(\|Q\|) | 可满足才执行，否则协商/fail-closed |

**正确性定理**：设需求集覆盖率为 1−α_n、共享证书满足定义 62 的多任务 soundness、且 RSC_t(B)≥1−β。则执行 B 后 Sat(N_t) 失败的概率 ≤ α_n+β（对需求覆盖与满足两个事件取并集界）；若 B(v,P)≥θ_safe(κ) 则安全绑定通过。若 RSC 不通过或冲突未澄清，系统返回协商集或 fail-closed，**不存在“静默执行未验证需求”的路径**。注意：若忽略干扰与相关（即用 r_i^ST 代替 r_i^MT），定理前提不成立，联合覆盖率会跌破名义 1−Σα_i——这正是本框架相对 v23 的关键增量。

## 4. 实验设计 E115–E120

| 实验 | 指标 | 门槛 |
|---|---|---|
| E115 需求集覆盖 | 独立审计覆盖率、集合平均大小 | 覆盖 ≥ 95%（α_n=0.05）；集合大小 ≤ 阈值 |
| E116 需求误判与澄清 | 欠指定指令澄清成功率、误判致安全违例 | 澄清成功 ≥ 90%；安全违例 0 |
| E117 单模型多任务精度 | 各任务 vs 专用模型、干扰矩阵稳定性 | 平均退化 ≤ 2%；I/ρ 重估方差 ≤ 0.05 |
| E118 联合覆盖有效性 | 独立证书 vs MT 膨胀证书的实际联合覆盖 | MT 证书联合覆盖 ≥ 1−Σα；独立证书显著跌破 |
| E119 能量-时延收益 | 共享主干 vs 模型动物园 | 能耗 ↓ ≥ 40%；时延 ↓ ≥ 30% |
| E120 100h 闭环 | 协商成功率、静默降级次数、安全违例 | 协商成功 ≥ 90%；静默降级 0；安全违例 0 |

回退策略：E115 覆盖 < 90% → 增大 α_n、缩小 Ĝ_t 候选集并要求澄清；E117 干扰超界 → 关键任务回退独立模型（放弃部分节能换 safe）；E118 独立证书仍达标 → 说明干扰可忽略，简化膨胀项；E120 协商过载 → 限制协商候选 top-k 并默认保守降级选项。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 需求集过大导致可满足性总失败、协商过载 | 高 | 校准 α_n 收紧集合；主动澄清；协商只返回 top-k 且带默认选项 |
| 干扰矩阵估计滞后导致半径偏小 | 高 | 保守先验上界 I_max；在线审计集持续重估；超界即回退独立模型 |
| 共享主干相关失效（一个遮挡同时骗过所有头） | 高 | 相关失效哨兵 + 安全关键任务保留独立冗余通道 |
| 协商选项本身不可执行或被用户误解 | 中 | 选项先过 SAB/能量/时延检查；要求显式确认再执行 |
| 记忆复用旧需求造成目标漂移 | 中 | MVR 命中必须经 RSC 按当前 N_t 复核，需求不符则丢弃 |
| 需求共形集与多任务证书双重保守导致可用性崩塌 | 中 | 分级安全级：低 κ 任务放宽膨胀；高 κ 任务严格 fail-closed |

## 6. 本轮最大风险

**一句话**：单模型多任务把能力压进共享表示、需求集又把目标变成不确定集合，二者叠加会让 RSC 在“看起来可满足”时其实优化了错误任务或低估了跨任务相关失效，证书 soundness 被悄悄破坏；因此必须在真实同批执行分布上校准干扰与相关性、对 Ĝ_t 做独立覆盖审计，并在任一环节无法认证时直接协商或 fail-closed，绝不信任逐任务独立校准。
