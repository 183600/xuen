# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配多模态策略 × 主动多模态交互消歧」IP-253~263；灵感循环新循环第 1 轮；本轮灵感：「服务设计」×「可靠性」）

> R69 给了闭环一张「嘴」（主动问）和一个「鼻子」（流似然第二意见），并用 aleatoric / epistemic 的二分取代了 R68 的单一标量。但它仍把两件事当成理所当然：
>
> 1. **交互是一次查询，不是一段服务旅程。** MINT 对每个候选信息动作算一步 VoI，减去一个手调常数 c(g)，argmax 完即止。可注视、探针、问句都有先后、时长、时机与机会成本；人不是被动的 oracle，问一次会改变他的负荷、注意与信任。真正决定成败的往往不是「这一问问得值不值」，而是「整段任务里，什么时候问、问几次、问完人还愿不愿意继续配合」。
> 2. **可靠性是一张单轮证书，不是一个长时程性质。** J_FLUID 说的是「这一轮安全」，不是「这项服务跨 episode / 跨班次 / 跨操作员仍然可靠」。它没有错误预算、没有共因失效、没有降级阶梯、没有服务恢复；它的 k 个正交证据源默认彼此独立——而现实中两个「正交通道」常常共享同一个人、同一颗相机、同一个基础模型，共因失效会让冗余在纸面上成立、在事故里归零。
>
> 本轮用两个灵感补齐这两个缺口：
> - **服务设计**把「求助」变成一条可设计的旅程：前台触点 / 后台证据 / 可见性线 / 关键时刻 / 恢复弧——问什么、何时问、问砸了怎么补救，都是蓝图的一部分；
> - **可靠性**把它变成可计量、可预算、可降级的长期性质：SLO、错误预算、共因冗余、人因可靠性、优雅退化、服务恢复，而不是一次性证书。
>
> 核心命题：**把 clarification 从「单步信息动作选择」升级为「有可靠性契约的服务旅程」：用交互服务蓝图定义触点与恢复弧，用人因可靠性 + 信任协同生产建模「问」对人的反作用，用错误预算与共因审计约束长时程风险，用降级阶梯保证问砸之后仍能安全落地。R69 是「单触点、无限预算、独立通道、无恢复」的退化情形，R68 是「预算为零 / 降级到 L2」的退化情形。** 命名 **SERVE-RAS**（Service-journey, Error-budget, Recovery-aware Verification & Escalation for Risk-Adaptive Systems）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证、还能问什么」，R70 问「**这段求助关系能不能长期可靠地维持；问砸了，谁来恢复，恢复不了，怎么退**」。

## 0. 直觉与动机

**灵感 1（服务设计 → 交互是一条有前台和后台的旅程）**
直觉：酒店不会把「问客人要什么」当成一个孤立动作；它有前台触点（问候、确认、道歉）、后台支撑（订单、库存、权限）、可见性线（哪些内部状态让客人看见），以及关键时刻（入住、退房、投诉）。R69 的 MINT 只有「前台的一次提问」，没有后台的证据供应链，也没有关键时刻概念。把 clarification 画成服务蓝图后，三个新问题自然浮现：(a) 哪些触点必须在低可逆时刻之前完成；(b) 哪些后台证据必须在触点前预热，否则问也是白问；(c) 每个触点失败后走哪条恢复弧。服务设计不是装饰，它把「问」从动作空间里的一个点，变成状态机里的一段路。

**灵感 2（可靠性 → 冗余不等于独立，证书不等于可靠）**
直觉：可靠性工程最痛的教训是共因失效：三套冗余液压共享同一个油路，三台服务器共享同一个交换机，三个「正交」证据源共享同一个疲惫的操作员。R69 的引理 18 写的是 P_wrong ≤ δ_p ρ^{k−1}，但 ρ 只是两两相关，挡不住「一次共同失败让所有源同时错」。更根本地，可靠性是长时程频率性质（MTBF、可用度、SLO），单轮 valid 证书无法推出「连续 8 小时服务可靠」。所以本轮把 k-orthogonal 升级为 **k_eff-orthogonal**，把 J_FLUID 升级为带 SLO、错误预算、降级级别与恢复日志的 J_SERVE。

**灵感 3（错误预算 → 把「可以问错几次」显式化，而不是藏在 λ 里）**
直觉：SRE 的错误预算把「可靠性目标」翻译成「还能失败多少次」：预算健康时可以冒进，预算耗尽时冻结变更。R69 的 resolution bonus 本质上是「用交互换效率」，但它没有给这种交换设一个可耗尽的账户，于是系统可以在信任已经变薄时继续问。错误预算把「问」变成一种要花预算的变更：每次错误交互扣款，恢复也扣款，预算低于阈值自动限制到关键时刻（L1），耗尽就回到 R68（L2）。这不是给系统发「可以错几次」的许可证，而是给「冒险」设一个必须持续充值、且能被审计的账户。

**灵感 4（服务恢复 → 问错不是终点，恢复弧才是可靠性的一部分）**
直觉：服务设计里有一个反直觉现象：一次被妥善处理的服务失败，可能比从未失败带来更高的信任（recovery paradox）。R69 的最大风险恰恰是「问错比不问更危险」，因为它没有恢复路径：一旦把错误答案盖上「已验证」的章，信任是一次性击穿的。SERVE-RAS 要求「无恢复弧不得提问」：acknowledge（承认不确定）、explain（解释为什么问）、re-ask⊥（换正交通道再问）、alternative（给可执行备选）、handover（交给远程操作员）。恢复本身也要过安全认证、也要花预算。恢复不是道歉话术，它是一个有成功概率、有延迟、有残余风险的可靠性组件。

**灵感 5（协同生产 → 人因可靠性是内生状态，不是常数 δ_p）**
直觉：R69 把人的回答可靠性当成外部给定的欺骗率 δ_p。但同一个人在被尊重、低负荷、看得懂机器人意图时，回答质量高；在被反复追问、高负荷、不理解为什么问时，会敷衍、会撒谎、会沉默。也就是说 q 是 (τ 信任, w 负荷, ℓ 可读性) 的函数，而 τ、w 又被机器人的提问改变。这构成一个反馈回路：问得不好 → 信任下降 → 回答更不可靠 → epistemic 更高 → 更想问 → 信任更低。这是「交互死亡螺旋」，控制回路稳定不代表服务关系稳定。可靠性工程必须把人的状态当成服务系统的一部分来建模，而不是当成一个固定失效率的零件。

## 1. 形式化定义（增量：定义 310–327）

**定义 310（SERVE-RAS 总览）** SERVE-RAS = (ISB, JRP, SERM, CCA, EBM, REC, TLM, LDR, J_SERVE)，继承 FLUID-RAS 的 FMP / AUD / MINT / CIA / FMA / RAS-WM†。三不变式：
(i) **旅程级预算硬约束**：任意滑动窗口内错误交互数不超过 token bucket，且信任下界违反概率 ≤ δ_τ；
(ii) **无恢复弧不得提问**：每个可执行前置触点必须在 ISB 中预注册至少一条通过安全认证的恢复弧，否则 g 作废、U_epi 视为未消解；
(iii) **服务级别连续**：降级每次至多一级，回到更高级必须同时满足「预算回补 + CCA 通过 + 信任下界恢复」，绝不允许为效率跳过安全级别。

**定义 311（交互服务蓝图 ISB）** ISB = (𝒯, ℬ, ℱ, L_vis, ℛ, MoT)。𝒯 为前台触点集，每点 g 带 (channel, Δt, rev(g), c_attn, p(y|g,M,o))，其中 rev(g) ∈ [0,1] 为可逆性、c_attn 为注意力/社交成本；ℬ 为后台证据阶段（COF 标定、FMA 似然、HRM 后验、账本回放）；ℱ ⊆ (𝒮×𝒜×𝒮) 为带时长的流程；L_vis 为可见性线，定义哪些内部状态必须对人可读（legibility 映射 ℓ）；ℛ 为恢复弧；MoT 为关键时刻集（定义 313）。

**定义 312（服务旅程）** 旅程 j = (g_1, …, g_m)，m ≤ m_max，总时长 ≤ T_journey。旅程状态为 (b, τ, w, B, level)，其中 b 为模式信念、τ 为信任、w 为负荷、B 为错误预算、level 为服务级别。触点可插入、跳过、重排，但受 MoT 优先级与恢复弧可达性约束。

**定义 313（关键时刻 MoT）** g ∈ MoT ⇔ rev(g) < ρ_rev 或 c_fail(g) > c_MoT，即问错的后果不可逆或不可承受（碰撞前、交接前、隐私边界、不可撤回的物理动作）。MoT 交互必须预留证据容量，且其恢复弧必须是「先避险、后补救」的两段式。

**定义 314（旅程价值 JVoI）** JVoI(j) = E[Σ_t γ^t ( I(M; y_t | h_t) − c_attn(g_t) − c_trust(g_t) )] + E[recovery option value]，受定义 310 的预算与信任约束。R69 的 MINT 是 m=1、c 为常数、无恢复、B=∞、τ 固定的特例。

**定义 315（信任-负荷协同生产动力学）** 隐状态 (τ_t, w_t)。回答可靠性
q_t = σ(α_0 + α_τ τ_t − α_w w_t + α_ℓ ℓ(g_t))。
转移：
τ_{t+1} = clip(τ_t + η_s·1[correct] − η_f·1[wrong] + η_r·1[recovered] − η_a·1[no-answer], 0, 1)，
w_{t+1} = clip(w_t + δ_ask·1[g_t≠∅] − δ_rest·Δt, 0, w_max)。
「问」由此不是无代价查询，而是改变被控对象（人）的状态转移。

**定义 316（人因可靠性模型 HRM）** 层级贝叶斯：操作员 j 的可靠度 θ_j ~ Beta(a,b)，回答正确概率 q = q(θ_j, channel, τ, w, ℓ)。安全决策使用下可信界 q_lo（如 5% 分位），效率决策使用后验均值。TLM 持续更新；新操作员/新班次使用保守先验，禁止把总体均值直接迁移到个体安全判定。

**定义 317（服务可靠性 SER）** SER(π) = P(完成 H 步任务且无未恢复的安全/信任失效)。用可靠性框图分解：旅程是串联阶段，证据源是并联冗余，但并联项按共因修正；SER = Π_stages R_stage，其中证据阶段 R_evidence = R_parallel(k_eff)（定义 318）。

**定义 318（共因失效与有效冗余 k_eff）** 共因因子 c ∈ [0,1]，共有失败概率 f_c，独立单源错误概率 f。k 源多数投票错误率
P_err(k) = c·f_c + (1−c)·Σ_{i>k/2} C(k,i) f^i (1−f)^{k−i}。
定义等效独立源数 k_eff 为独立系统达到同一错误率所需的源数，并保守取 k_eff = 1 + (k−1)(1−c)。证据纪律由 R69 的 k ≥ 2 升级为 k_eff ≥ k_min（默认 2）；k_eff 不足 ⇒ U_epi 不消解、resolution bonus 不发放。

**定义 319（错误预算与 SLO）** token bucket B(t) ∈ [0, B_max]，以 r_B 回补；一次错误交互消耗 1，一次恢复消耗 β_rec。SLO 三元组：(ρ_wrong ≤ ρ_SLO, ρ_int ≤ ρ_int,max, P(T_rec ≤ T_rec,max) ≥ 1−δ_rec)。EBM 维护 B 与滑动窗口 SLO 估计，并为待发放的 resolution bonus 做托管（定义 326）。

**定义 320（服务降级阶梯 LDR）** L0 全交互旅程；L1 仅 MoT（禁止探索性提问）；L2 继承 R68 纯保守（不问，λ=λ_floor(U_ale+U_epi)）；L3 安全停 / 远程接管 / 人工复位。转移 δ(level, B, τ_lo, ECE, SER_hat)；每次至多降一级，升一级需证据，L3 为吸收态直到人工复位。级别只改变交互权限与 λ 下界，不改变当前动作的安全包络。

**定义 321（服务恢复控制器 REC）** ℛ = {acknowledge, explain, re-ask⊥, alternative, handover}。恢复成功概率 r_rec(τ, ρ)，恢复延迟 T_rec，残余不确定性 U_epi⁺，恢复后信任 τ⁺。恢复动作本身必须过 C-RAS-WM 认证（例如 handover 不得在危险姿态下突然撒手）。若存在 ρ 使 τ⁺ > τ_before，则发生 recovery paradox。

**定义 322（恢复感知旅程规划 JRP）** 在状态 (b, τ, w, B, level) 上求解受限半马尔可夫决策：max_π JVoI s.t. E[#wrong] ≤ B、P(τ < τ_min) ≤ δ_τ、恢复弧可达。滚动时域深度 d ≤ 3；默认 d=1 且关闭恢复即精确退化为 R69 的 MINT。求解用 constrained rollout / Lagrangian，候选触点 ≤ 5，MoT 优先剪枝。

**定义 323（信任-交互账本 TLM）** append-only、hash-chained 账本，记录 (touchpoint, context_hash, outcome, recovery, trust_update, operator_id_hash, isb_version, hrm_version)。用于 HRM 更新、SLO 统计、证书连续性与事后审计；对外只存摘要与差分隐私统计，原文不出设备。

**定义 324（服务审计 VQAuditor-S）** 升级 VQAuditor-I，审计旅程级决策：MoT 是否被尊重、每个已执行触点是否真有恢复弧并被演练、是否用仪表盘掩盖信任下降、错误预算是否被 Goodhart 化（为花预算而问 / 为省预算而不问）、共因是否被低估。结论回灌 HRM、EBM、CCA 先验。

**定义 325（服务证书 J_SERVE）** J_SERVE = (J_FLUID, SLO_snapshot, B(t), SER_hat + CI, k_eff, level, recovery_log_hash, trust_estimate + CI, isb_version, hrm_version)。Valid ⇔ Valid(J_FLUID) ∧ SLO 未违约 ∧ 级别一致 ∧ 每个已执行触点有恢复弧 ∧（使用 resolution bonus ⇒ k_eff ≥ k_min 且 B ≥ B_escrow）∧ 账本哈希链接连续无缺口。

**定义 326（resolution bonus 托管）** R69 的 resolution bonus 只有在其潜在恢复成本被预算托管后才可发放：
E_res(g) = c_rec·P(wrong|g) + c_hand·P(unrecoverable|g)。
仅当 B(t) − E_res(g) ≥ B_reserve 且 CCA 通过时，λ = λ_floor(U_ale)；否则 U_epi 计入 λ_floor。这把 R69 的「消歧成功即放松」改成「有恢复能力才放松」。

**定义 327（跨班次/跨本体可靠性迁移）** 层级模型在操作员/机队间共享先验、在 TLM 分片上局部更新；新操作员使用 q_lo，禁止用总体均值做安全判定。ISB 与 JRP 的版本必须与 J_SERVE 绑定（isb_version, hrm_version），跨版本证书不得拼接。

```python
# IP-264 ISB：交互服务蓝图（前台触点 + 后台证据 + 恢复弧 + MoT）
class ServiceBlueprint:
    def touchpoints(self, state): ...                  # 候选 g，带 rev / c_attn / info_model
    def mot_only(self): ...                            # L1：仅关键时刻可用
    def recovery_arcs(self, g, failure_modes): ...     # 每个失败模式至少一条弧
    def has_certified_recovery(self, g): ...           # “无恢复弧不得提问”

# IP-265 JRP：恢复感知、预算受限的旅程规划（d=1 + 无恢复 ⇒ R69 MINT）
class JourneyPlanner:
    def plan(self, b, tau, w, budget, level, depth=3):
        cands = M.blueprint.mot_only() if level == L1 else M.blueprint.touchpoints(b)
        return constrained_rollout(cands, depth, budget, tau, M.serm, M.recovery)

# IP-267 CCA：共因审计后的有效冗余（替掉 R69 的名义 k）
def effective_k(sources, ledger):
    c = estimate_common_cause(sources, ledger)         # 共享人/传感器/模型 → c↑
    return 1 + (len(sources) - 1) * (1 - c), c

# IP-268 EBM：错误预算 + SLO + bonus 托管
class ErrorBudgetManager:
    def spend(self, outcome): self.B -= 1.0 if outcome.wrong else 0.0
    def escrow(self, g):
        need = c_rec * P_wrong(g) + c_hand * P_unrecoverable(g)
        return self.B - need >= B_reserve
    def slo_ok(self): return self.rho_wrong <= RHO_SLO and self.rho_int <= RHO_INT

# IP-269 REC：服务恢复（先避险，后补救；恢复也过 C-RAS-WM）
def recover(incident, tau, level):
    for rho in [ACK, EXPLAIN, REASK_ORTH, ALTERNATIVE, HANDOVER]:
        if not c_ras_wm.certify_recovery(rho, incident.state): continue
        if rho_cost(rho) > M.ebm.B: continue
        return execute_recovery(rho, incident)
    return escalate_to_L3(incident)

# IP-272 HRM：人因可靠性（内生信任/负荷），TLM 在线更新
def q_lower(op, channel, tau, w, legibility):
    return posterior_quantile(op, channel, tau, w, legibility, q=0.05)

# IP-275 主闭环（继承 FLUID-RAS，仅在交互处置处插入服务/可靠性层）
def SERVE_RAS_round(M, obs):
    z, o = M.mtm.forward(...); c, U_cal, thr = M.cof.step(...)
    K = 1 if M.fmp.mode_head(z) < TAU_MODE else 4
    samples = M.fmp.sample(o, K)
    U_ale, U_epi, modes, _ = M.aud.decompose(samples, z, M.fmp.mode_head)

    # 1) 可靠性状态：有效冗余、信任下界、服务级别
    k_eff, c_cc = M.cca.effective_k(M.evidence_sources, M.ledger)
    tau, w = M.trust.state(); q_lo = M.hrm.q_lower(..., tau, w)
    level = M.ldr.step(B=M.ebm.B, tau=tau, ece=M.mcg.ece,
                       ser=M.serm.estimate(level=M.ldr.level_now, k_eff=k_eff, q=q_lo))
    if level >= L2:                                     # 精确退化为 R68
        return M.r68_round(z, o, U_ale + U_epi, U_cal)

    # 2) 旅程规划；无恢复弧 / 预算不足 / 冗余不足 ⇒ 不问
    g = M.jrp.plan(modes, tau, w, M.ebm.B, level, depth=3 if level == L0 else 1)
    if g is not None and not M.blueprint.has_certified_recovery(g): g = None
    if g is not None and (k_eff < M.k_min or not M.ebm.escrow(g)): g = None

    # 3) 执行 + 恢复 + 证据纪律（k_eff 而非名义 k）+ 账本
    rec = None
    if g is not None:
        out = M.cia.execute(g)                          # 看 / 问 / 触，过 C-RAS-WM
        if out.is_failure:
            rec = M.recovery.recover(out, tau, level)   # 先避险，后补救
        U_epi = M.cia.update_belief(modes, out, discipline=k_eff)
        M.trust.update(out, rec); M.ebm.spend(out)
        M.ledger.append(g, out, rec, tau, M.isb.version)

    # 4) 风险缩放：只有被托管且恢复可达的 resolution 才放松
    U_floor = U_ale + (U_epi if (g is None or rec is None or not rec.ok) else 0.0)
    lam = max(M.efs.risk_scale(...), lam_floor(U_floor))
    A = M.ach.propose(x_prime, H=M.vista.H)
    k = M.c_ras_wm.certified_prefix(A, ..., wm_preds)
    if M.fma.slow_fault(...):
        lam = max(lam, 0.8); k = min(k, k_cal_shrink(A, U_cal)); level = max(level, L2)

    # 5) 执行 + 参与式服务审计 + 证书
    mode = select_mode(modes, U_epi, lam)
    tau_cmd = M.pi_sigma.prefix_dispatch(mode.a[:k]) * lam
    M.vqa_s.submit_async(g, out if g else None, rec, tau, B=M.ebm.B, level=level)
    return k, lam, mode, (U_ale, U_epi), level
```

## 3. 推导

**假设 A99–A102。** A99（恢复完备）：每个可执行触点对 ℰ_poison × ℰ_flow 中每个失败模式都有已认证恢复弧，且 r_rec ≥ r_min；A100（级别滞回）：LDR 每次至多变一级且升一级需证据；A101（托管可靠）：E_res 是潜在恢复成本的保守上界；A102（模型可校准）：CCA 的 c 与 HRM 的 q_lo 在部署域内有覆盖，分布外时自动收紧。

**引理 19（旅程价值的子模性与贪心缺口）** 若触点信息增益对证据单调子模、成本可加、且信任/负荷不随交互变化，则 JVoI 是单调子模函数，带预算的贪心达到 (1−1/e) 近似。反之，在协同生产下，早期失败会降低后续触点的 q（边际价值下降），而恢复又能抬高 q（边际价值回升），二者叠加破坏子模性。构造：一个低价值早期问题可把信任压到 τ_min 以下，使真正的 MoT 问题无法被回答；贪心选早期问题，JRP 选择等待。故 R69 的「一步最优」只在「问不改变人」的假设下近似成立。

**引理 20（共因下冗余的饱和）** 由定义 318，若 c·f_c ≥ δ*，则任意 k 都不能把错误率压到 δ* 以下；即使 c·f_c < δ*，有效冗余也只有 k_eff ≈ 1 + (k−1)(1−c)，当 c→1 时 k_eff→1。故 ρ<1 不足以推出冗余有效，必须排除共同失败模式；增加通道在共因高时只增加成本、不增加可靠性。R69 的引理 18 应改写为 P_wrong ≤ c·f_c + (1−c)·δ_p ρ^{k−1} + ε_σ，并以 k_eff 作为实际可用的冗余度。

**引理 21（信任死亡螺旋与恢复阈值）** 令 q(τ) 为回答正确概率，交互后的信任期望漂移
D(τ) = q(τ)η_s + (1−q(τ))[ r_rec η_r − (1−r_rec)η_f ]。
若 q 随 τ 递增，则低信任区可能 D(τ)<0，形成正反馈坍缩。健康不动点存在的必要条件是 D(τ_min) ≥ 0，即
r_rec ≥ r* = ( η_f − q(τ_min)η_s/(1−q(τ_min)) ) / ( η_r + η_f )。
当 q(τ_min)→0 且 η_f 大时 r*→1：再好的恢复也救不回。故恢复必须被测量、被纳入 SLO，并在设计中留出 r_rec > r* 的裕度；它不是礼貌，而是与安全认证同级的可靠性组件。

**定理 18（FLUID 与 R68 的双重严格包含）** 在 A99–A102 下：
(i) 令 ISB 只含单触点、B=∞、关闭恢复、τ 固定、k_eff=k，则 SERVE 与 FLUID 逐指令相同；
(ii) 令 B=0 或 level ≥ L2 或 k_eff < k_min 或 SLO 违约，则 SERVE 与 R68/CALM 保守路径逐指令相同；
(iii) 中间区间，物理风险不超过 FLUID 的 ε_int（信息动作仍过 C-RAS-WM 认证），未恢复风险由定理 20 的预算上界约束。
故 SERVE 不是替代 R68/R69，而是在「服务旅程 × 可靠性」两个维度上把二者包成边界。

**定理 19（降级连续与有界升级）** 在 A100 下：(i) 级别变化只改变交互权限与 λ 下界，不改变当前动作的安全包络，故控制指令连续无突变；(ii) 持续 SLO 违约时，系统在有限轮内到达 L3（级别势函数单调下降）；(iii) 无持续扰动时不会在相邻级别抖动（滞回 + 预算回补需证据）。安全侧由 C-RAS-WM 认证独立保证，与级别无关。

**定理 20（错误预算的安全-效率 Pareto）** 设单次错误交互的未恢复代价上界 c_w、恢复成本 c_r、预算 B。则期望未恢复损失 ≤ R68_baseline + B·c_w；期望效率增益 ≤ bonus(B)，且 bonus 对 B 单调、Lipschitz。最优预算 B* 满足边际 bonus 等于边际风险 c_w 的加权。故 R69 的激进交互对应 B→∞ 的高风险端点，R68 对应 B=0；SERVE 把这个连续谱显式化，并允许按任务风险等级选择 B。

## 6. 本轮最大风险

**一句话**：SERVE-RAS 的全部保证押在两个无法从数据中完全验证的量上——**人因可靠性 q 与信任动力学 D(τ)**；若把 SRE 式错误预算当 KPI，系统会学会「把预算花完」或在信任已崩时仍出示「服务正常」的仪表盘；更根本地，有些 moment of truth（碰撞、跌落、隐私泄露）不可恢复，把它们当作「可恢复的服务事故」是范畴错误——**可靠性工程可以给服务记账，但不能替不可逆的物理后果买单**。

**次级风险与缓解**：
1. **共因审计自欺**（把共享通道判成独立）→ 引理 20 的饱和界 + CCA 周期重估 + E303/E315；
2. **恢复表演化**（道歉/解释很多、实际未恢复）→ 恢复成功率与延迟进 SLO，VQAuditor-S 抽查，E304/E305；
3. **信任模型分布外**（儿童、老人、敌对用户、脆弱群体）→ q_lo 安全判定 + 分布外收紧 + 保守先验，E308/E309；
4. **错误预算 Goodhart 化**（为花预算而问 / 为省预算而不问）→ 双指标（漏问率与错问率）+ 审计 + 定理 20 的 Pareto 约束；
5. **级别抖动/降级过慢** → 滞回 + 势函数 + 定理 19，E306/E311；
6. **账本隐私与责任** → 差分隐私摘要 + 哈希链 + 版本绑定，E312。

```python
        cands = M.blueprint.mot_only() if level == L1 else M.blueprint.touchpoints(b)
        return constrained_rollout(cands, depth, budget, tau, M.serm, M.recovery)

# IP-267 CCA：共因审计后的有效冗余
def effective_k(sources, ledger):
    c = estimate_common_cause(sources, ledger)         # 共享人/传感器/模型 → c↑
    return 1 + (len(sources) - 1) * (1 - c), c

# IP-268 EBM：错误预算 + SLO + bonus 托管
class ErrorBudgetManager:
    def spend(self, out): self.B -= 1.0 if out.wrong else 0.0
    def escrow(self, g):
        need = c_rec * P_wrong(g) + c_hand * P_unrecoverable(g)
        return self.B - need >= B_reserve
    def slo_ok(self): return self.rho_wrong <= RHO_SLO and self.rho_int <= RHO_INT

# IP-269 REC：先避险后补救；恢复也过 C-RAS-WM
def recover(incident, tau, level):
    for rho in [ACK, EXPLAIN, REASK_ORTH, ALTERNATIVE, HANDOVER]:
        if not c_ras_wm.certify_recovery(rho, incident.state): continue
        if rho_cost(rho) > M.ebm.B: continue
        return execute_recovery(rho, incident)
    return escalate_to_L3(incident)

# IP-272 HRM：人因可靠性（安全用下可信界）
def q_lower(op, channel, tau, w, legibility):
    return posterior_quantile(op, channel, tau, w, legibility, q=0.05)

# IP-275 主闭环（继承 FLUID-RAS）
def SERVE_RAS_round(M, obs):
    z, o = M.mtm.forward(...); c, U_cal, thr = M.cof.step(...)
    K = 1 if M.fmp.mode_head(z) < TAU_MODE else 4
    samples = M.fmp.sample(o, K)
    U_ale, U_epi, modes, _ = M.aud.decompose(samples, z, M.fmp.mode_head)

    k_eff, c_cc = M.cca.effective_k(M.evidence_sources, M.ledger)
    tau, w = M.trust.state(); q_lo = M.hrm.q_lower(..., tau, w)
    level = M.ldr.step(B=M.ebm.B, tau=tau, ece=M.mcg.ece,
                       ser=M.serm.estimate(M.ldr.level_now, k_eff, q=q_lo))
    if level >= L2:                                     # 精确退化为 R68
        return M.r68_round(z, o, U_ale + U_epi, U_cal)

    g = M.jrp.plan(modes, tau, w, M.ebm.B, level,
                   depth=3 if level == L0 else 1)
    if g is not None and not M.blueprint.has_certified_recovery(g): g = None
    if g is not None and (k_eff < M.k_min or not M.ebm.escrow(g)): g = None

    rec = None
    if g is not None:
        out = M.cia.execute(g)                          # 看/问/触，过 C-RAS-WM
        if out.is_failure:
            rec = M.recovery.recover(out, tau, level)   # 先避险，后补救
        U_epi = M.cia.update_belief(modes, out, discipline=k_eff)
        M.trust.update(out, rec); M.ebm.spend(out)
        M.ledger.append(g, out, rec, tau, M.isb.version)

    U_floor = U_ale + (U_epi if (g is None or rec is None or not rec.ok) else 0.0)
    lam = max(M.efs.risk_scale(...), lam_floor(U_floor))
    A = M.ach.propose(x_prime, H=M.vista.H)
    k = M.c_ras_wm.certified_prefix(A, ..., wm_preds)
    if M.fma.slow_fault(...):
        lam = max(lam, 0.8); k = min(k, k_cal_shrink(A, U_cal)); level = max(level, L2)

    mode = select_mode(modes, U_epi, lam)
    tau_cmd = M.pi_sigma.prefix_dispatch(mode.a[:k]) * lam
    M.vqa_s.submit_async(g, out if g else None, rec, tau, B=M.ebm.B, level=level)
    return k, lam, mode, (U_ale, U_epi), level
```

## 4. 推导

**引理 19（旅程价值的子模性与贪心缺口）** 若触点信息增益单调子模、成本可加、且信任/负荷不随交互变化，则 JVoI 单调子模，带预算贪心达到 (1−1/e) 近似。协同生产下，早期失败降低后续 q、恢复又抬高 q，破坏子模性；一个低价值早期问题可把信任压到 τ_min 以下，使真正的 MoT 问题无法被回答。故 R69 的「一步最优」只在「问不改变人」时近似成立。

**引理 20（共因下冗余的饱和）** 若 `c·f_c ≥ δ*`，任意 k 都不能把错误率压到 δ* 以下；即使 `c·f_c < δ*`，`k_eff≈1+(k−1)(1−c)`，`c→1` 时 `k_eff→1`。故 ρ<1 不足以推出冗余有效；R69 引理 18 应改为 `P_wrong ≤ c·f_c + (1−c)·δ_p ρ^{k−1} + ε_σ`，并以 k_eff 作为实际冗余度。

**引理 21（信任死亡螺旋与恢复阈值）** 信任漂移
`D(τ)=q(τ)η_s+(1−q(τ))[r_rec η_r−(1−r_rec)η_f]`。
健康不动点存在的必要条件 `D(τ_min)≥0`，即
`r_rec ≥ r* = (η_f − q(τ_min)η_s/(1−q(τ_min))) / (η_r + η_f)`。
当 `q(τ_min)→0` 且 `η_f` 大时 `r*→1`：再好的恢复也救不回。恢复因此是与安全认证同级的可靠性组件，必须进 SLO。

**定理 18（FLUID 与 R68 的双重严格包含）** 在 A99–A102 下：(i) 单触点、B=∞、关闭恢复、τ 固定、k_eff=k 时，SERVE 与 FLUID 逐指令相同；(ii) B=0 或 level≥L2 或 k_eff<k_min 或 SLO 违约时，SERVE 与 R68/CALM 逐指令相同；(iii) 中间区间物理风险不超过 FLUID 的 ε_int，未恢复风险由定理 20 的预算上界约束。

**定理 19（降级连续与有界升级）** 级别变化只改交互权限与 λ 下界，不改安全包络 ⇒ 控制连续无突变；持续 SLO 违约下有限轮内到达 L3（势函数单调）；无持续扰动时不抖动（滞回 + 升级需证据）。

**定理 20（错误预算的安全-效率 Pareto）** `E[未恢复损失] ≤ R68_baseline + B·c_w`；`E[效率增益] ≤ bonus(B)`，且 bonus 对 B 单调、Lipschitz；最优 B* 满足边际 bonus = 边际风险 c_w 的加权。R69 对应 B→∞，R68 对应 B=0。

## 7. 本轮最大风险

**一句话**：SERVE-RAS 的全部保证押在两个无法从数据中完全验证的量上——**人因可靠性 q 与信任动力学 D(τ)**；若把 SRE 式错误预算当 KPI，系统会学会「把预算花完」或在信任已崩时仍出示「服务正常」的仪表盘；更根本地，有些 moment of truth（碰撞、跌落、隐私泄露）不可恢复，把它们当作「可恢复的服务事故」是范畴错误——**可靠性工程可以给服务记账，但不能替不可逆的物理后果买单**。

**次级风险与缓解**：共因审计自欺（引理 20 饱和界 + CCA 周期重估 + E303/E315）；恢复表演化（r_rec/T_rec 进 SLO + VQAuditor-S + E304/E305）；信任模型分布外（q_lo + 分布外收紧 + 保守先验 + E308/E309）；错误预算 Goodhart 化（漏问率与错问率双指标 + 审计 + 定理 20 Pareto 约束）；级别抖动/降级过慢（滞回 + 势函数 + 定理 19 + E306/E311）；账本隐私与责任（差分隐私摘要 + 哈希链 + 版本绑定 + E312）。
