# 第 1 轮 · PRO-SIMPLEX：把 VLA 当「不可信高级控制器」，用本体感知残差监控 + 安全技能库把失败拦在 180 秒内

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新灵感循环第 1 轮，三个词是「容错控制」「本体感知」「ROS」。本轮不推倒上一版第 12 轮 CHUNK-SERVO，而是把它从「执行层」推进到「运行时保障层」：VLA 仍然是唯一的学习模型，负责语义规划；新增的是一个**无学习权重、可在 CPU 上每个 chunk 边界跑一次**的确定性监控器，以及一个**有限状态安全技能库**。一句话：**不要求 VLA 不出错，而是要求它在出错后 1 个 chunk 内被接住。**

## 0. 先给结论：榜首不到 30%，「失败检测 + 恢复」比「再大 1B」更便宜

截至 2026-10-31，官网榜单仍是 8 个模型：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。头尾只差 9.2pp。榜单 JSON 仍是 `gen_leaderboard.py` 生成，32 任务步骤分与成功率线性相关（R²≈0.9999996–0.9999999，最大残差<0.006），运行记录页 256/256 条但详情视频仍是占位。**这些数字只能当预览，不能当 SOTA 或失败分布。**

但有一个信号是可靠的：**所有模型都在 70% 以上的任务上失败**。这说明赛事的主要矛盾不是「语义不够强」，而是「执行不可靠」。再训一个更大的 VLA，边际收益是几个百分点；而一个能在失败发生后 167ms–333ms 内接管、退回、重试的运行时保障层，可能把同一批失败 trial 中的一部分直接翻成成功。它不增加第二个学习模型，不违反单模型规则，CPU 开销可以忽略。

本轮的押注是 **PRO-SIMPLEX**：

> 把官方 WLA/VLA 当作 Simplex 架构里的 **Advanced Controller（AC，不可信高级控制器）**；把「本体感知残差监控器 + 故障隔离 + 确定性安全技能库」当作 **Baseline Controller（BC，可信基线）**；在固定 chunk 边界上做切换。VLA 负责「做什么」，PRO-SIMPLEX 负责「做砸了怎么办」。

三个可验证创新点：

1. **多残差故障指纹**：不是单一阈值，而是 8 类残差（action-lead、ARX 动态、delta、FK 一致性、夹爪、视觉 edit、时序、下身体）组成的故障签名矩阵；用成功演示校准，不需要失败数据。
2. **Chunk-boundary Simplex**：承认 API 不能在 chunk 内打断，把「反应时间」显式建模为 `H_c/f_c`；用固定短 chunk + 计划缓存 + 安全技能 chunk，把故障恢复做成可证明的有限状态机。
3. **ROS 2 离线故障注入台**：用 URDF/TF/FK、`rosbag2` 回放、MuJoCo/IsaacLab 和故障注入代理节点，在提交前把 F1–F8 故障跑一遍；ROS 2 只做实验室仪器，不上提交链路。

### 1.3 API：四路 RGB、无深度/力/触觉、chunk 内不能打断

提交模板（2026-10-31 复核）给出：

- 观测：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB 480×640；双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str`。
- 动作：`joint` 或 `ee` 互斥；`action_chunk_size` 是 metadata 中的固定整数；index 0 先执行，其余按顺序执行，直到 evaluator 再次调用 `get_action`。
- **chunk 内没有新观测，也没有打断机制。** 评测端逐调用记录延迟、波动和动作统计规律。
- **没有 depth、camera_info、force/torque、tactile。** 腕部相机在数据集中也没有内参矩阵。

**关键推论**：如果 `H_c=5`、控制 30Hz，监控器每 **167ms** 才能看一次世界；故障检测延迟下界是 `H_c/f_c`，不是「实时」。所谓「自适应 chunk」不能改 chunk 长度，只能做**固定 chunk 内的计划缓存、边界监控、下一 chunk 切换安全技能**。这是本轮最硬的接口事实，也是 PRO-SIMPLEX 的边界条件。

### 1.6 失败检测已经很热，但都不适配「单模型 + 远程 API + chunk 边界」

| 工作 | 会议/年份 | 信号 | 需要失败数据 | 运行时 | 为什么不能直接搬 |
|---|---|---|---|---|---|
| **Sentinel** | CoRL 2024 | 动作时序一致性 STAC + VLM 进度 | 否 | 是 | 需要采样多批动作 + VLM 调用；延迟/成本高；没有恢复 |
| **FIPER** | NeurIPS 2025 | RND OOD + action-chunk entropy + conformal | 否 | 是 | 需要多次采样 chunk 和策略 embedding；RND 是第二个学习模型 |
| **FAIL-Detect** | RSS 2025 | OOD + conformal | 否 | 是 | 在观测 embedding 上训 flow 模型；第二个学习模型 |
| **SAFE** | NeurIPS 2025 | VLA 内部特征 + MLP/LSTM + conformal | 是 | 是 | 需要内部特征和失败数据；第二个学习头 |
| **ProTracer** | arXiv 2026 | 本体感知关键帧 + VLM 诊断 | 否 | 事后 | 是诊断，不是控制；VLM 延迟 |
| **CoPRE** | arXiv 2026 | 无接触本体感知力矩残差，G1 上 82.2% recall、5.5N 90% | 否 | 是 | 只做接触检测；需要力矩估计；没有隔离/恢复 |
| **Foundational World Models** | ICRA 2026 | 世界模型不确定性 + conformal | 否 | 是 | 重；第二个世界模型；双腕线缆任务 |
| **GAP** | ICLR 2026 | 视觉-本体感知失败机理 | n/a | 训练期 | 解释「为什么失败」，不是运行时监控 |
| **Black-Box Simplex** | NFM 2022 | 运行时保障，AC→BC 切换 | n/a | 是 | 通用 CPS，没有 VLA/API/chunk 实例 |

**共同缺口**：

1. **检测多、恢复少**。大多数工作停在「报警」，没有把报警接到「hold/retreat/re-grasp/re-approach/re-plan」的确定性技能上。
2. **学习多、解析少**。SAFE/FIPER/FAIL-Detect 都要第二个学习组件；单模型规则下，这要么违规，要么需要把检测头塞进同一个 checkpoint（API 不暴露特征，做不到）。
3. **离线多、chunk 边界少**。没有人把「chunk 内不能打断」当作一等约束来设计监控器；而 UniBot 的 API 正是这个约束。
4. **单臂多、双臂/人形少**。CoPRE 在 G1 上验证了本体感知接触检测，但只做接触，不覆盖 F1/F2/F5/F6/F7/F8，也没有利用另一只手臂和 lower_body。

**PRO-SIMPLEX 的差异化**：确定性、无学习权重、成功演示校准、只用 API 可见信号、CPU 每个 chunk 边界跑一次、带故障隔离和安全技能、显式建模 chunk 延迟。它不是「又一个 failure detector」，而是「把 failure detector 接到 Simplex 控制架构上」。

## 2. 诊断：三个「来不及」

把一次失败拆开看：

```text
t0: 观测 o_k → VLA 推理 (100-300ms) → 返回 30 步计划
t0+0.1s: evaluator 开始执行 chunk
t0+0.1s … t0+1.1s: 机器人开环执行 30 步
        ↑ 接触、滑移、人移动物体都发生在这一段
t0+1.1s: 才看到下一帧 → 已经晚了
```

三个「来不及」：

1. **规划来不及**：30 步 chunk = 1 秒开环；接触发生在最后 3 厘米、最后 0.3 秒。
2. **检测来不及**：如果监控器只在 chunk 边界看，故障最早在下一个边界被发现；`H_c=30` 就是 1 秒延迟。
3. **恢复来不及**：就算检测到了，如果只会「停」，任务还是失败；必须有「退回—重试—重新规划」的技能。

CHUNK-SERVO 解决第 1 个：把 30 步计划切成 5 步执行块，用视觉伺服修正最后 3 厘米。PRO-SIMPLEX 解决第 2、3 个：在 5 步边界上监控，发现故障就丢掉剩余计划，执行一个确定性安全技能 chunk，然后再让 VLA 重新规划。两者是**串联**关系，不是替代关系。

## 3. 方法：PRO-SIMPLEX

### 3.1 总架构

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)       │
                    │  ├─ plan cache (30-step VLA plan)   │
                    │  ├─ chunk slicer (H_c=3/5/10)       │
                    │  ├─ residual monitor (8 residuals)  │
                    │  ├─ fault isolator (signature)      │
                    │  ├─ safe skill FSM (6 skills)       │
                    │  └─ action adapter (WLA → API)      │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared VLA server (GPU)            │
                    │  UnifoLM-WLA-1.0 / VLA-0, 30-step   │
                    └─────────────────────────────────────┘
```

关键设计：**evaluator 看到的 `action_chunk_size` 是 `H_c`（例如 5），但 PolicyService 内部仍然让 WLA 生成 30 步计划并缓存；每次 `get_action` 返回下一段 5 步。** 这样既保留了 30 步的语义规划，又把反馈周期降到 5 步；如果故障发生，丢弃缓存，执行安全技能 chunk，再重新调用 VLA。`H_c` 在 episode 开始前静态选定，不在 episode 中动态改变。

### 3.2 故障分类 F1–F8

| 编号 | 故障 | 典型场景 | 主要残差 | 首选安全技能 |
|---|---|---|---|---|
| F1 | 观测 stale / dropout | 相机丢帧、网络抖动 | R7 时序、R6 视觉 | HOLD → RE_PLAN |
| F2 | 执行器卡死 / 饱和 | 关节不动、夹爪不闭合 | R1 action-lead、R3 delta | RETREAT → RE_PLAN |
| F3 | 碰撞 / 卡阻 | 插入偏了、撞到杯沿 | R1、R2、R4 | RETREAT → RE_APPROACH |
| F4 | 夹爪滑移 / 掉落 | 抓杯子滑、插头掉 | R5 夹爪、R6 视觉 | RE_GRASP |
| F5 | 外部扰动 / 人为干扰 | 人移动物体、推手臂 | R1、R2、R8 | HOLD → RE_PLAN |
| F6 | 运动学 / 传感器不一致 | FK 与 EE 位姿不一致 | R4 FK 一致性 | HOLD → ABORT |
| F7 | 网络 / 延迟 | RTT 突增、chunk 迟到 | R7 时序 | HOLD |
| F8 | 端口 / 模型服务故障 | 某端口无响应、键名错 | R7 + 服务健康 | ABORT / 重连 |

### 3.3 八类残差

| 残差 | 定义 | 作用 | 注意 |
|---|---|---|---|
| **R1 action-lead** | `e_k = s_{k+lag} - a_k`，lag=2–3 帧 | 检测执行器没跟上指令 | 动作/状态共同的恒定偏置会在差分中抵消，必须用「变化」而非「绝对值」 |
| **R2 ARX 动态** | `s_{t+1} = A[s_t, a_t, Δa_t, 1] + ε` | 检测动力学异常 | 线性模型，不是学习策略；按任务/手臂校准 |
| **R3 delta** | `Δs_t - Δs_{t-1}` 的异常 | 检测卡死/突变 | 对噪声敏感，需平滑 |
| **R4 FK 一致性** | `FK(q_t) - p_t^{EE}` | 检测关节/EE 不一致、TF 错 | 需要 URDF 和关节顺序；离线标定 |
| **R5 夹爪** | 夹爪闭合指令 vs 实际闭合/物体距离 | 检测滑移/空抓 | 腕部视觉/夹爪开合；没有电流 |
| **R6 视觉 edit** | 当前腕部图 vs 演示目标图的 SSIM/ORB 差异 | 检测「没进展」 | 经典 CV，不用学习模型；目标图从成功演示检索 |
| **R7 时序** | `Δt_k`、丢帧、chunk 迟到 | 检测 F1/F7 | 只依赖时间戳，最便宜 |
| **R8 下身体** | `lower_body`/waist 速度、base 稳定性 | 检测 F5 外部扰动 | 人形独有；单臂任务也要看 |

### 3.4 决策模块：CUSUM + 故障签名 + 保守默认

对每个残差 `r_k`，用成功演示估计均值 `μ` 和标准差 `σ`，做标准化 `z_k = |r_k - μ| / σ`，再用 CUSUM：

```text
g_k = max(0, g_{k-1} + z_k - ν)
alarm if g_k > h
```

`ν` 是容忍漂移，`h` 是报警阈值；二者用成功演示的 p99 校准，目标是每 episode 假阳性 <1 次（约 <0.5%/chunk）。故障隔离用一个签名矩阵：每类故障在哪些残差上「应该」报警；取与当前报警模式最匹配的故障，若匹配度低于阈值，默认 `HOLD + RE_PLAN`（保守，不猜）。

**主动臂门控**：只监控正在执行任务的手臂；空闲手臂的残差没有信息量，反而增加假阳性。HangCup 的离线实验显示，右臂（空闲/辅助）的 ARX p95 和检测率都明显差于左臂，直接支持这个门控。

### 3.5 安全技能库：6 个确定性 chunk 生成器

| 技能 | 行为 | 时长 | 前置条件 | 后置条件 |
|---|---|---|---|---|
| **HOLD** | 保持当前 EE 位姿/关节，夹爪保持 | 1–2 chunks | 任何故障 | 稳定、无碰撞 |
| **RETREAT** | 沿 -approach 方向慢退 2–5cm | 1–2 chunks | F2/F3/F5 | 离开接触面 |
| **RE_APPROACH** | 沿 approach 方向慢进，带小螺旋搜索 | 2–4 chunks | F3 且目标仍在 | 回到预接触位 |
| **RE_GRASP** | 张开→对准→闭合→轻抬 | 2–3 chunks | F4 | 夹住或确认空抓 |
| **RE_PLAN** | 调用同一 VLA 重新规划 | 1 次推理 | F1/F5/F3 | 新计划可用 |
| **ABORT** | 退回安全位，放弃本 trial | 1–2 chunks | F6/F8 或连续失败 | 不损坏场景 |

所有技能都是**有限状态机 + 几何轨迹**，没有学习权重；它们只生成「短动作 chunk」，不生成任务级语义动作。技能参数（速度、距离、时长）用成功演示和仿真校准，保守优先。

### 3.6 Chunk-boundary 监督器

```text
on get_action(obs):
    if first_call or plan_cache empty:
        plan = VLA(obs)                  # 30 steps
        cache = plan
    if monitor says fault:
        cache = []                       # discard remaining plan
        action = safe_skill(obs, fault)  # H_c steps
        state = RECOVERING
    else:
        action = cache[:H_c]             # next slice
        cache = cache[H_c:]
    return action
```

- **不能在 chunk 内打断**：安全技能最早在下一个 `get_action` 生效；所以 `H_c` 是反应时间的硬下限。
- **检测延迟**：`H_c/f_c` + CUSUM 累积延迟；`H_c=5` 约 167ms，`H_c=3` 约 100ms。
- **计划缓存**：30 步计划只生成一次，6 个 5 步切片；切片之间可以叠加视觉伺服修正（CHUNK-SERVO），但修正幅度受限，避免破坏计划。
- **恢复后**：`RE_PLAN` 调用同一 VLA，不引入第二个模型；`reset()` 清空缓存、CUSUM、技能状态。

### 3.7 ROS 2：只做离线故障注入台

官方提交接口是 Python websocket + msgpack，不是 ROS。**不要把 ROS 2 放上提交链路**：DDS discovery、QoS、序列化、额外进程和端口隔离都会增加延迟和故障面。ROS 2 的正确位置是实验室：

- `unitree_ros` URDF + `robot_state_publisher` + `tf2`：离线验证 FK 一致性（R4）和坐标系。
- 故障注入代理节点：订阅 `/joint_states`、`/tf`、`/camera/...`、`/policy/action`，发布 F1–F8 的 corrupted 版本（丢帧、延迟、冻结、饱和、TF 偏移、动作截断）。
- `rosbag2`：录制/回放成功演示和故障场景，带 `/clock`；用于可复现实验。
- `unitree_mujoco` / `unitree_sim_isaaclab`：作为 plant，注入碰撞、滑移、外部扰动。
- `diagnostic_updater` / lifecycle：健康状态和技能状态的可视化；运行时用 Python 复刻同一状态机。

## 4. 三个灵感词怎么落到方案里

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **容错控制** | Simplex 架构（AC=VLA，BC=安全技能库）、F1–F8 故障分类、CUSUM、故障签名、chunk 边界切换、恢复后重规划 | 不做底层关节级容错控制（API 不掌控底层）；不做第二个学习策略 |

| **ROS** | 离线故障注入台、URDF/TF/FK、rosbag2 回放、MuJoCo/IsaacLab、diagnostic/lifecycle | 不把 ROS 2 当提交接口；不在关键路径上加 DDS/QoS/桥接 |

## 5. 离线实验：先证明「残差有信息」，再证明「不是万能」

### 5.1 数据与对齐

通过 `datasets-server.huggingface.co/rows` 抓取：

- `G1_Dex1_HangCup`：800 行，5 episodes。
- `G1_Dex1_PlugInEthernet`：800 行，1 episode。

对每个候选 lag（0–5 帧）计算 action 与下一帧 state 的 EE 位置残差，最佳 lag 为 **2–3 帧**。lag=3 的平均残差（mm）：

| 任务/手臂 | x | y | z |
|---|---:|---:|---:|
| HangCup 左 | +0.7 | -0.3 | **-10.2** |
| HangCup 右 | -0.4 | +0.1 | **-14.5** |
| PlugInEthernet 左 | -0.4 | -0.3 | **-8.4** |
| PlugInEthernet 右 | +2.6 | +0.8 | **-5.7** |

z 方向的系统性偏置说明：**不能直接拿「指令位姿 - 当前位姿」的绝对值做故障阈值**；它会把正常的 TCP/坐标系偏差当成故障。

### 5.2 ARX 动态残差

用 `s_{t+1} = A[s_t, a_t, Δa_t, 1]` 拟合成功轨迹，按 episode 划分训练/测试，held-out 的 p95：

| 任务/手臂 | p95 位置残差 |
|---|---:|
| HangCup 左 | **3.3 mm** |
| HangCup 右 | 4.6 mm |
| PlugInEthernet 左 | **5.2 mm** |
| PlugInEthernet 右 | 22.2 mm |

结论：主动臂上，线性 ARX 已经能把「正常动力学」压到毫米级，足够做残差监控；右臂/辅助臂的残差大，说明**不能一刀切**，必须按任务/手臂/相位校准。

### 5.3 故障注入

在成功轨迹上注入合成故障，阈值取 clean p99、连续 2 帧触发：

| 故障 | HangCup 左 | PlugInEthernet 左 |
|---|---:|---:|
| 1cm offset | **100%** | — |
| 2cm offset | **100%** | **40%** |
| 0.2cm/帧 drift | **100%** | — |
| stuck | **61%** | **30%** |
| delay | **61%** | **30%** |
| FPR | **~0%** | **0.3%** |

右臂/空闲臂的检测率明显更差；`stuck` 和 `delay` 是最难的，因为残差信号小，单帧阈值不够，需要 CUSUM 和多残差融合。

### 5.4 解释与限制

- **恒定 offset 会被 ARX 的 state 输入吸收**：R2 对「慢慢漂」敏感，对「突然偏 1cm 但稳定」不敏感；必须用 R1 action-lead 和 R3 delta 补。
- **任务/手臂差异大**：HangCup 左臂好，PlugInEthernet 左臂差；不能用一套阈值跑 32 任务。
- **合成故障不是真实失败**：这些数字只证明「残差有信息」，不证明「真机成功率会涨」。必须过 G3–G6。
- **负结果**：朴素的「ARX + 单阈值」不够；这直接剪掉了「一个残差打天下」的方案。

## 6. 与 CHUNK-SERVO 的关系：升级，不是替代

| 层 | CHUNK-SERVO（上一版） | PRO-SIMPLEX（本轮） |
|---|---|---|
| 目标 | 最后 3 厘米的精度 | 失败后的生存与恢复 |
| 机制 | 30 步计划 + 5 步视觉伺服 | 30 步计划缓存 + 5 步边界监控 + 安全技能 |
| 信号 | 视觉相对位姿/目标图 | 本体感知残差 + 视觉 edit |
| 失败时 | 继续伺服，可能越修越偏 | 丢弃计划，HOLD/RETREAT/RE_GRASP/RE_PLAN |
| 合规 | 确定性控制器 | 确定性监控器 + 确定性技能，仍无第二个学习模型 |
| 收益 | 接触任务 +4–7pp（上一版估计） | 人为干扰 +1–2pp、接触恢复 +1–2pp，**增量 +2–4pp** |

**不要重复计算**：CHUNK-SERVO 的收益是「本来能做对但差 3 厘米」；PRO-SIMPLEX 的收益是「本来会失败、但被接住」。两者交集是接触任务；在估计总收益时取保守增量，不把两个 +5pp 相加。

## 7. 剪枝清单（本轮明确不做）

- **动态 chunk 长度**：`action_chunk_size` 是 metadata 固定值，不能在 episode 中改；只做静态 `H_c` 选择 + 计划缓存。
- **30Hz 广域网视觉伺服**：RTT 不允许；只在 chunk 边界做。
- **学习型失败检测器**：SAFE/FIPER/FAIL-Detect 都要第二个学习组件；单模型规则下风险高。
- **力/触觉闭环**：API 没有；CoPRE 的力矩残差也拿不到，只能用位置/EE/FK 残差。
- **关节级容错控制**：不掌控底层；只做 EE/关节目标层的安全技能。
- **世界模型做故障预测**：太重，且可能是第二个模型；Foundational World Models 的路线不适合远程 API。
- **ROS 2 上提交链路**：DDS/QoS/桥接/端口隔离都不划算；ROS 2 只做离线。
- **第二个 VLA/残差策略**：违反单模型精神；安全技能是几何轨迹，不是策略。
- **把榜单任务排名当难度表**：榜单是预览/合成；只用它当「所有模型都失败」的证据。

## 8. 可验证创新点与收益估算

### 8.1 三个可验证创新点

1. **多残差故障指纹 + 成功演示校准**：在 HangCup/PlugInEthernet 上，主动臂 ARX p95 3.3–5.2mm；合成故障 1–2cm offset 100%/40%，stuck/delay 30–61%；G1/G3 验证 FPR 和检测延迟。
2. **Chunk-boundary Simplex + 安全技能 FSM**：把「不能 chunk 内打断」变成设计约束；G2/G4 验证 `H_c=3/5/10` 的反应时间与恢复成功率；G5/G6 验证真机收益。
3. **ROS 2 离线故障注入台**：URDF/TF/FK + rosbag2 + MuJoCo/IsaacLab + F1–F8 注入；G3 验证可复现性和隔离准确率；不上提交链路。

### 8.2 收益估算（保守）

- 人为干扰轴占 20%（64/320 trials）；human +5–10pp → 全局 **+1–2pp**。
- 接触任务（19/32 A 档）恢复 +5pp；A 档共 190 trials（非 human 152），按失败子集折算 → 全局 **+1–2pp**。
- 合计 **+2–4pp 增量**，与 CHUNK-SERVO 的 +4–7pp 不重复相加；如果 G5/G6 不过，收益按 0 计。
- 步骤分：早停/早恢复可能减少 180s 超时，作为 tie-breaker 有额外价值，但不计入主收益。

## 9. 风险与合规

- **单模型**：监控器和技能库零学习权重；只有 WLA/VLA 生成任务级动作；如果官方把「任何额外计算」当模型，走 C1（纯解析）而不是 C3（同 checkpoint 特征）。
- **API**：没有 chunk 内打断、depth、force、wrist 内参、task ID、goal image；方案只依赖语言指令 + 四路 RGB + 本体感知 + 成功演示库。
- **假阳性**：安全技能可能打断成功 trial；用保守阈值、CUSUM、主动臂门控、默认 HOLD+RE_PLAN；G1/G5 必须测 FPR。
- **安全**：HOLD/RETREAT 慢速、限幅、工作空间约束；诊断出 F5（外部扰动/人为干扰）优先退让，不推人、不加速。
- **证据**：离线故障是合成的；必须过 G3–G6 才能声称真机收益；本报告把相关结论标 C 级。
- **ROS 2**：只做离线；提交链路是 Python websocket/msgpack；避免 DDS/QoS/端口隔离的额外风险。

## 10. 一句话押注

**如果 UniBot 的瓶颈是「VLA 会失败」而不是「VLA 不会做事」，那么最便宜的涨分点不是再训一个更大的模型，而是给现有 VLA 加一个 167ms 内接管、会退回/重试/重规划的确定性 Simplex 层。**

# 第 1 轮产物 · PRO-SIMPLEX 技术报告

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本报告是第 1 轮想法区「PRO-SIMPLEX」的工程化产物；它把上一版第 12 轮 CHUNK-SERVO 作为执行层基线，在其上增加运行时保障层，不替换其视觉伺服与计划缓存。

## 0. 结论与边界

### 0.1 一句话结论

官方 WLA 的 30 步 action chunk 是吞吐优势，也是故障反应时间的结构性下限；把 evaluator 看到的 `action_chunk_size` 降到 `H_c=3–5`，内部缓存 30 步计划，在每个 chunk 边界用**无学习权重的本体感知残差监控器**检测 F1–F8 故障，再用**确定性安全技能库**执行 HOLD/RETREAT/RE_APPROACH/RE_GRASP/RE_PLAN/ABORT，可以在不新增第二个学习模型的前提下，把「失败后继续错下去」改成「一个 chunk 内被接住」。离线实验证明主动臂的 ARX 残差可以压到 3.3–5.2mm，合成 1–2cm offset 的检测率 100%/40%，但 stuck/delay 只有 30–61%；因此本方案的核心不是「检测率 100%」，而是**多残差 + 保守默认 + 恢复技能**。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、排行榜 JSON 直接核实 | 规则、API、33,276 eps、WLA `chunk_size=30`、榜单 29.7% |
| B | 我们在公开数据/网页上做的分析，可复现 | 榜单 `step~success` 回归、运行记录 256/256、动作-状态 lag、ARX p95 |
| C | 设计假设，需 G0–G7 验证 | 真机 +5pp、人为干扰 +5–10pp、`H_c=5` 稳定、安全技能恢复 ≥50% |

### 0.3 本轮不做什么

- 不从零训 VLA/World Model；官方 WLA 已开源 6B 基座。
- 不做完整 sim-to-real 策略训练；仿真只做故障注入和技能验证。
- 不做第二个学习模型/残差策略/失败分类器；监控器和技能库是解析/几何/统计组件。
- 不做力/触觉闭环；API 没有，CoPRE 的力矩残差也拿不到。
- 不做 6D 物体位姿网络；视觉 edit 用经典 CV + 成功演示检索。
- 不做动态 chunk 长度；`action_chunk_size` 是 metadata 固定值。
- 不做 30Hz 广域网伺服；只在 chunk 边界做修正。
- 不把 ROS 2 当提交接口；官方只认 Python `PolicyService` 的 websocket/msgpack 接口。
- 不把预览榜单的任务排名当实测难度；只当「所有模型都失败」的证据。

### 1.2 提交 API（A）

提交模板 README（2026-10-31 复核）给出：

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640** |

#### 1.4.1 WLA 输出键与挑战赛键的映射

WLA model server 的输出：

```text
action.left_ee_rpy    (1, T, 6)  xyz + rpy, composed onto the current left EE
action.right_ee_rpy   (1, T, 6)  xyz + rpy, composed onto the current right EE
action.left_gripper   (1, T, 1)
action.right_gripper  (1, T, 1)
action.pivot          (1, T, 7)  vx, vy, vw, yaw, pitch, roll, height
```

挑战赛期望：

```text
action.left_ee_pose_gripper_base   (1, T, 6)
action.right_ee_pose_gripper_base  (1, T, 6)
action.left_gripper                (1, T, 1)
action.right_gripper               (1, T, 1)
action.pivot                       (1, T, 7)
```

映射：

| WLA | 挑战赛 | 变换 |
|---|---|---|
| `action.left_ee_rpy` | `action.left_ee_pose_gripper_base` | 键名重映射；确认 xyz+rpy 约定、base 系、绝对/相对 |
| `action.right_ee_rpy` | `action.right_ee_pose_gripper_base` | 同上 |
| `action.left_gripper` | `action.left_gripper` | 直接 |
| `action.right_gripper` | `action.right_gripper` | 直接 |
| `action.pivot` | `action.pivot` | 直接；顺序 `vx, vy, vw, yaw, pitch, roll, height` |

**注意**：WLA 的 `action.left_ee_rpy` 是在当前 EE 上 compose 相对 xyz+rotvec 后的**绝对** xyz+rpy；挑战赛的 `*_pose_gripper_base` 也是绝对目标位姿。因此主要风险不是「相对/绝对」，而是 **rpy 顺序、旋转表示、base 系定义、以及 `gripper_base` vs `gripper_torso` 的坐标系差异**。必须在单任务通道用静止/小动作回放验证。

#### 1.4.2 计划缓存与 `action_chunk_size`

WLA server 默认返回 30 步；挑战赛 evaluator 按 metadata 的 `action_chunk_size` 执行。为了既保留 30 步规划又获得 5 步反馈，PolicyService 采用**外层短 chunk + 内层长计划**：

```text
metadata.action_chunk_size = H_c = 5
PolicyService.get_action(obs):
    if cache empty:
        plan30 = WLA(obs)          # 30 steps
        cache = plan30
    action5 = cache[:5]
    cache = cache[5:]
    return action5
```

这是合法的：evaluator 只看到 5 步；WLA 仍然是同一个模型；计划缓存只是控制器状态。缺点是计划基于第一次观测，6 个切片后才重新规划；CHUNK-SERVO 的视觉伺服可以在切片内做小幅修正。若故障发生，丢弃 cache，执行安全技能，再调用 WLA 重新规划。

## 2. 问题形式化

### 2.1 Chunk-boundary supervisor

设控制频率 `f_c`，chunk 长度 `H_c`，第 `k` 个边界时刻 `t_k = k H_c / f_c`。evaluator 在 `t_k` 给观测 `o_k`，PolicyService 返回动作 chunk `A_k = (a_{k,0}, …, a_{k,H_c-1})`；evaluator 执行整个 chunk，期间没有新观测、没有打断。监控器只能在 `t_{k+1}` 看到执行结果。

```text
o_k = (images_k, q_k, p_k^EE, g_k, lower_body_k, language)
A_k = π(o_k)                  # VLA policy, 30-step plan sliced to H_c
s_{k+1} = Plant(s_k, A_k)     # unknown, stochastic, possibly faulty
```

监控器 `M` 在 `t_{k+1}` 计算残差 `r_{k+1}`，输出故障假设 `f_{k+1}` 或 `none`；决策模块 `D` 选择继续/安全技能；安全技能 `S` 生成下一个 chunk。

**反应时间**：

```text
T_react >= H_c / f_c + T_CUSUM + T_compute
```

`T_CUSUM` 是 CUSUM 累积到阈值所需的 chunk 数；`T_compute` 是监控器计算时间（目标 <5ms）。`H_c=5`、30Hz、CUSUM 1–2 chunks → 约 167–500ms；`H_c=30` → 1–2s，基本来不及。

### 2.2 故障分类 F1–F8

| 编号 | 故障 | 观测特征 | 主要残差 | 隔离难点 | 首选技能 |
|---|---|---|---|---|---|
| F1 | 观测 stale/dropout | 时间戳跳变、图像重复/黑屏 | R7、R6 | 与网络延迟混淆 | HOLD → RE_PLAN |
| F2 | 执行器卡死/饱和 | 关节/EE 不跟随指令、速度≈0 | R1、R3 | 与「故意停」混淆 | RETREAT → RE_PLAN |
| F3 | 碰撞/卡阻 | EE 位置停滞、ARX 残差大、视觉无进展 | R1、R2、R4 | 与 F2 混淆 | RETREAT → RE_APPROACH |
| F4 | 夹爪滑移/掉落 | 夹爪闭合但物体相对位移、腕部图变化 | R5、R6 | 需要视觉/物体跟踪 | RE_GRASP |
| F5 | 外部扰动/人为干扰 | EE/下身体被推、轨迹突变 | R1、R2、R8 | 与 F2/F3 混淆 | HOLD → RE_PLAN |
| F6 | 运动学/传感器不一致 | FK(q) 与 EE 位姿长期不一致 | R4 | 需要 URDF/关节顺序 | HOLD → ABORT |
| F7 | 网络/延迟 | chunk 迟到、RTT 突增、动作重复 | R7 | 与 F1 混淆 | HOLD |
| F8 | 端口/模型服务故障 | 无响应、键名/形状错、超时 | R7 + 健康检查 | 需要进程级监控 | ABORT/重连 |

### 2.3 残差定义

设 `s_t` 为 EE 位姿（或关节向量），`a_t` 为动作，`q_t` 为关节角，`p_t` 为 EE 位姿，`g_t` 为夹爪开合，`I_t` 为腕部图。

**R1 action-lead**：

```text
e_t^lead = s_{t+lag} - a_t,  lag = 2..3 frames
z_t^lead = |e_t^lead - μ_lead| / σ_lead
```

用「变化」而不是「绝对值」：`Δe_t^lead = e_t^lead - e_{t-1}^lead`；恒定 offset 不报警，突变/漂移报警。

**R2 ARX 动态**：

```text
s_{t+1} = A [s_t, a_t, Δa_t, 1] + ε_t
r_t^ARX = s_{t+1} - \hat s_{t+1}
z_t^ARX = |r_t^ARX - μ_ARX| / σ_ARX
```

`A` 用成功演示做线性最小二乘（可加岭正则）；不是神经网络。按任务/手臂/相位分模型。

**R3 delta**：

```text
r_t^Δ = Δs_t - Δs_{t-1}
```

检测卡死（Δ≈0）和突变（|Δ| 大）。

**R4 FK 一致性**：

```text
r_t^FK = FK(q_t) - p_t^EE
```

需要 URDF 和关节顺序；如果 `r_t^FK` 长期偏大，可能是 TF/传感器故障（F6），而不是任务失败。

**R5 夹爪**：

```text
r_t^grip = |g_t - g_t^cmd|
```

加上腕部视觉的物体相对位移；如果夹爪闭合但物体远离，判 F4。

**R6 视觉 edit**：

```text
r_t^vis = 1 - SSIM(I_t^wrist, I_t^goal)
```

`I^goal` 从成功演示库按语言 + 初始图检索；经典 CV，不用 CLIP/学习模型。也可用 ORB 匹配数/光流。

**R7 时序**：

```text
r_t^time = t_t^recv - t_{t-1}^recv - H_c/f_c
```

丢帧、迟到、重复都体现在这里。

**R8 下身体**：

```text
r_t^base = |v_t^base| + |ω_t^waist|
```

人形独有；F5 外部扰动时 base/waist 会动。单臂任务也要看，避免「手被推、身体在动」被误判为手臂故障。

### 2.4 CUSUM 与故障隔离

对每个残差：

```text
z_k = |r_k - μ| / σ
g_k = max(0, g_{k-1} + z_k - ν)
alarm_k = (g_k > h)
```

`ν` 控制容忍漂移，`h` 控制报警灵敏度；用成功演示的 p99 校准，目标每 episode 假阳性 <1 次（约 <0.5%/chunk）。CUSUM 的好处是：单帧小残差（stuck/delay）可以累积；单帧大残差（offset）立即触发。

**故障签名矩阵** `S[f, r] ∈ {0,1}`：每类故障在哪些残差上「应该」报警。当前报警向量 `b` 与每行做匹配：

```text
score_f = <b, S[f]> / (||b||_1 + ε)
f* = argmax_f score_f
if max score < τ: f* = HOLD_REPLAN
```

保守默认：不确定时 `HOLD + RE_PLAN`，不猜 `RETREAT`（可能撞到别的东西）。

**主动臂门控**：

```text
if arm is idle: disable R1/R2/R3/R5 for that arm
```

HangCup 离线实验显示右臂（辅助/空闲）ARX p95 4.6mm，但故障检测率明显低于左臂；空闲臂的残差主要是噪声，监控它只会增加假阳性。

### 2.5 安全技能的可达性与安全性

安全技能不是「任意轨迹」，而是**预定义、短时、低速、工作空间内**的几何轨迹：

- HOLD：保持当前 EE 位姿，夹爪保持；速度 0，最安全。
- RETREAT：沿 `-approach` 方向退 2–5cm；`approach` 由当前 EE 朝向或演示中的接近方向估计；速度 ≤2cm/s。
- RE_APPROACH：沿 `+approach` 慢进，带 ±5mm 小螺旋；速度 ≤1cm/s。
- RE_GRASP：张开到演示的开度 → 对准 → 闭合 → 轻抬 1cm；力/电流不可得，用位置+视觉确认。
- RE_PLAN：调用同一 VLA；如果 VLA 仍输出故障动作，连续 2 次失败 → ABORT。
- ABORT：退回安全位，结束 trial；不损坏场景。

安全性约束：

```text
q_min <= q <= q_max
|q_dot| <= q_dot_max
p_EE in workspace
no self-collision (URDF + simple capsules)
if F5 diagnosed (external perturbation, possibly human): only HOLD/RETREAT, no RE_APPROACH
```

```python
    cusum: dict[str, float]       # R1-R8
    fault: str | None             # F1-F8 / none
    skill: str | None             # HOLD/RETREAT/...
    skill_steps: int
    last_obs: Observation
    last_action: Action
    episode_id: int
```

`reset()` 清空所有状态；端口之间不共享可变状态；共享的只有只读的校准表/WLA 客户端。

### 3.3 监控器

每个 chunk 边界：

```python
def monitor(obs, last_obs, last_action, state):
    residuals = {}
    residuals["R1"] = action_lead(obs, last_action)
    residuals["R2"] = arx(obs, last_obs, last_action)
    residuals["R3"] = delta(obs, last_obs)
    residuals["R4"] = fk_consistency(obs)
    residuals["R5"] = gripper(obs, last_action)
    residuals["R6"] = visual_edit(obs)
    residuals["R7"] = timing(obs)
    residuals["R8"] = base_motion(obs)
    alarms = cusum_update(residuals, state.cusum)
    fault = isolate(alarms)
    return fault, residuals, alarms
```

目标：<5ms/边界/端口；纯 NumPy；不调用 GPU；不阻塞 websocket。

### 3.4 决策模块

```python
def decide(fault, alarms, obs, state):
    if fault is None:
        return "CONTINUE"
    if fault in ("F1", "F7"):
        return "HOLD_THEN_REPLAN"
    if fault in ("F2", "F3"):
        return "RETREAT_THEN_REPLAN"
    if fault == "F4":
        return "RE_GRASP"
    if fault == "F5":
        return "HOLD_THEN_REPLAN"   # human: no approach
    if fault == "F6":
        return "HOLD_THEN_ABORT"
    if fault == "F8":
        return "ABORT"
    return "HOLD_THEN_REPLAN"
```

连续失败计数：同一故障连续 2 次 → 升级（HOLD→RETREAT→ABORT）；恢复成功后清零。

### 3.5 安全技能库

```python
def skill_chunk(skill, obs, H_c):
    if skill == "HOLD":
        return hold(obs, H_c)
    if skill == "RETREAT":
        return retreat(obs, H_c, distance=0.03, speed=0.02)
    if skill == "RE_APPROACH":
        return re_approach(obs, H_c, spiral=0.005, speed=0.01)
    if skill == "RE_GRASP":
        return re_grasp(obs, H_c)
    if skill == "RE_PLAN":
        return vla(obs, H_c)          # same model
    if skill == "ABORT":
        return abort(obs, H_c)
```

每个技能返回 `H_c` 步动作，形状与 API 一致；`RE_PLAN` 是唯一调用 VLA 的技能，仍然只有一个模型。

### 3.7 时序预算

| 阶段 | 预算 | 备注 |
|---|---:|---|
| 观测解码/预处理 | 5–10ms | 四路 RGB；可 resize |
| VLA 推理（仅重规划） | 100–300ms | 6B，4 步扩散；不是每个 chunk 都跑 |
| 监控器 | <5ms | 纯 NumPy，CPU |
| 安全技能生成 | <1ms | 几何轨迹 |
| websocket 序列化/传输 | 5–20ms | 取决于 RTT |
| chunk 执行 | `H_c/f_c` | H_c=5 → 167ms |

关键：监控器不能在每个边界调用 VLA；只有 `RE_PLAN` 或计划缓存耗尽时才调用。否则 6B 推理会把 167ms 的反馈周期吃光。

## 4. 残差库与校准

### 4.1 R1 action-lead

- 目的：检测执行器没跟上指令（F2/F3/F5）。
- 计算：`e_t = s_{t+lag} - a_t`；`lag=2–3` 帧（67–100ms）。
- 校准：用成功演示的 `Δe_t` 的 p99；不用绝对 `e_t`，因为存在 0.6–1.5cm 的 z 偏置。
- 故障注入：1cm offset 在 HangCup 左 100% 检测；2cm offset 在 PlugInEthernet 左 40%；说明它擅长「突变」，不擅长「小偏移」。

### 4.2 R2 ARX

- 目的：检测动力学异常（F3/F5）。
- 计算：`s_{t+1} = A[s_t, a_t, Δa_t, 1]`；`A` 用线性最小二乘（可加岭正则）。
- 校准：按任务/手臂/相位分模型；held-out p95 3.3–5.2mm（主动臂）。
- 限制：恒定 offset 会被 `s_t` 吸收；必须配合 R1/R3。

### 4.3 R3 delta

- 目的：检测卡死/突变（F2）。
- 计算：`Δs_t - Δs_{t-1}`；用滑动窗口平滑。
- 限制：噪声大；阈值要按速度自适应。

### 4.4 R4 FK 一致性

- 目的：检测 F6（TF/传感器/关节顺序错）。
- 计算：`FK(q_t) - p_t^EE`；用 URDF 和关节顺序。
- 校准：离线用 `unitree_ros` + `tf2` 验证；运行时用轻量 Pinocchio/URDF 解析。
- 限制：如果 API 的 EE 位姿不是 base 系，先做坐标变换；`gripper_base` vs `gripper_torso` 必须确认。

### 4.5 R5 夹爪

- 目的：检测 F4（滑移/空抓）。
- 计算：`|g_t - g_t^cmd|` + 腕部视觉物体相对位移。
- 校准：成功演示的夹爪闭合曲线；失败注入：夹爪闭合但物体远离。
- 限制：没有力/电流；只能靠位置+视觉。

### 4.6 R6 视觉 edit

- 目的：检测「没进展」（F1/F3/F4）。
- 计算：`1 - SSIM(I_t^wrist, I_t^goal)`；或 ORB 匹配数。
- 目标图：从成功演示库按语言 + 初始图检索；同一任务/相位。
- 限制：腕部无内参；光照/遮挡敏感；只作为辅助残差，不单独决策。

### 4.7 R7 时序

- 目的：检测 F1/F7。
- 计算：`Δt_k - H_c/f_c`；丢帧、迟到、重复。
- 校准：单任务通道测 RTT 分布；阈值取 p99 + 50ms。
- 限制：与 F1 混淆；需要图像重复检测辅助。

### 4.8 R8 下身体

- 目的：检测 F5（人推/外部扰动）。
- 计算：`|v_base| + |ω_waist|`；用 `lower_body` 差分。
- 校准：成功演示的 base 运动；人形任务中 base 可能主动移动，需按任务门控。
- 限制：单臂桌面任务 base 通常静止；阈值可以很严。

### 4.9 校准流程

```text
for each task, arm, phase:
    1. 从成功演示取 N 条轨迹
    2. 对齐 action/state（lag=2-3）
    3. 拟合 ARX A（线性最小二乘/岭正则）
    4. 计算 R1-R8 的 μ, σ, p99
    5. 设 ν = p95(z), h = p99(g)（或按目标 FPR 反推）
    6. 在 held-out 成功轨迹上测 FPR
    7. 在合成故障上测检测率/延迟
    8. 写入 calibration.json（只读，端口共享）
```

校准表是**数据**，不是模型权重；它不生成动作，只提供阈值。若官方对「模型」作最宽解释，校准表仍属于统计参数，不是第二个策略。

## 5. 离线实验

### 5.1 数据

通过 `https://datasets-server.huggingface.co/rows?dataset=...` 抓取：

- `G1_Dex1_HangCup`：800 行，5 episodes。
- `G1_Dex1_PlugInEthernet`：800 行，1 episode。

字段：`observation.state.left_ee_pose_gripper_base`、`action.left_ee_pose_gripper_base`、`observation.state.left_gripper`、`action.left_gripper`、`frame_index`、`episode_index` 等。只取前 800 行，不是完整数据集；结论是可行性检查，不是基准。

### 5.2 动作-状态对齐

对 lag=0…5 计算 `s_{t+lag} - a_t` 的 EE 位置残差；最佳 lag 为 **2–3 帧**（67–100ms）。lag=3 的平均残差（mm）：

| 任务/手臂 | x | y | z | 范数 |
|---|---:|---:|---:|---:|
| HangCup 左 | +0.7 | -0.3 | **-10.2** | 10.2 |
| HangCup 右 | -0.4 | +0.1 | **-14.5** | 14.5 |
| PlugInEthernet 左 | -0.4 | -0.3 | **-8.4** | 8.4 |
| PlugInEthernet 右 | +2.6 | +0.8 | **-5.7** | 6.3 |

解释：

- z 方向系统偏置 0.6–1.5cm；可能是 TCP/坐标系/动作前瞻。
- 直接用绝对残差做阈值会把正常偏置当故障；必须用变化/校准后的残差。
- lag 2–3 帧意味着「动作指令」比「实际状态」超前 67–100ms；监控器要用 `a_t` 对 `s_{t+lag}`，而不是同一帧。

### 5.3 ARX 动态残差

模型：

```text
s_{t+1} = A [s_t, a_t, a_t - a_{t-1}, 1] + ε
```

按 episode 划分训练/测试（HangCup 3 训练/2 测试；PlugInEthernet 1 episode 内部按时间切分），held-out p95：

| 任务/手臂 | p95 位置残差 |
|---|---:|
| HangCup 左 | **3.3 mm** |
| HangCup 右 | 4.6 mm |
| PlugInEthernet 左 | **5.2 mm** |
| PlugInEthernet 右 | 22.2 mm |

解释：

- 主动臂上，线性 ARX 已能把正常动力学压到毫米级；足够做残差监控。
- 右臂/辅助臂的 p95 22.2mm，说明它要么运动更复杂，要么数据更少；不能一刀切。
- ARX 是线性系统辨识，不是学习策略；它只预测下一帧 EE，不生成任务动作。

### 5.4 故障注入

在成功轨迹上注入合成故障；阈值取 clean p99，连续 2 帧触发：

| 故障 | HangCup 左 | PlugInEthernet 左 |
|---|---:|---:|
| 1cm offset | **100%** | — |
| 2cm offset | **100%** | **40%** |
| 0.2cm/帧 drift | **100%** | — |
| stuck | **61%** | **30%** |
| delay | **61%** | **30%** |
| FPR | **~0%** | **0.3%** |

右臂/空闲臂的检测率明显更差；`stuck` 和 `delay` 是最难的，因为残差信号小，单帧阈值不够，需要 CUSUM 和多残差融合。

### 5.5 解释与限制

**正面**：

- 主动臂 ARX 残差毫米级，说明「正常」可以被紧凑建模。
- 1–2cm offset、0.2cm/帧 drift 在 HangCup 左臂 100% 检测，FPR≈0。
- 这证明「成功演示校准的解析残差」是可行的，不需要失败数据。

**负面**：

- 恒定 offset 会被 ARX 的 state 输入吸收；R2 单独不够，必须 R1/R3。
- PlugInEthernet 左臂 2cm offset 只有 40%，stuck/delay 30%；任务差异大。
- 右臂/空闲臂效果差；必须主动臂门控 + 按任务校准。
- 合成故障不是真实失败；这些数字不能直接外推到真机成功率。

**结论**：本轮不押「检测率 100%」，押「多残差 + 保守默认 + 恢复技能」；离线实验只用于筛选残差和设阈值，真机收益必须过 G3–G6。

## 6. ROS 2 离线故障注入台

### 6.1 为什么不上提交链路

官方提交接口是 Python websocket + msgpack，`PolicyService` 在 8765 起 N 个端口独立监听。ROS 2 上提交链路会引入：

- DDS discovery / QoS / 序列化开销；
- 额外进程和桥接（ROS↔websocket/msgpack）；
- 端口隔离和 `reset()` 状态隔离更难保证；
- 延迟和故障面增加，评测端会记录调用延迟。

因此：**ROS 2 只做离线故障注入台和数字孪生；提交链路保持纯 Python。**

### 6.2 节点图

```text
┌─────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│ unitree_mujoco  │────▶│ /joint_states    │────▶│ fault_injector  │
│ / IsaacLab      │     │ /tf              │     │ (F1-F8)         │
└─────────────────┘     │ /camera/...      │     └────────┬────────┘
                        │ /policy/action   │              │
                        └──────────────────┘              ▼
                                                   ┌─────────────┐
                                                   │ PolicyService│
                                                   │ + monitor    │
                                                   └──────┬──────┘
                                                          │
                        ┌──────────────────┐              │
                        │ rosbag2 recorder │◀─────────────┘
                        │ /monitor/*       │
                        └──────────────────┘
```

节点：

- `robot_state_publisher` + `unitree_ros` URDF：发布 `/tf`、FK。
- `fault_injector`：订阅正常话题，发布 corrupted 话题；支持 F1–F8 场景。
- `policy_bridge`：把 ROS 观测转成 `PolicyService` 输入，把动作转回 ROS；仅离线。
- `monitor_logger`：记录残差、报警、决策、技能状态。
- `rosbag2`：录 `/joint_states`、`/tf`、`/camera/*`、`/policy/action`、`/monitor/*`。

### 6.3 故障场景

| 场景 | 注入方式 | 目标故障 | 期望 |
|---|---|---|---|
| S1 | 丢 `/joint_states` 5 帧 | F1 | R7 报警，HOLD |
| S2 | 冻结左臂关节 10 帧 | F2 | R1/R3 报警，RETREAT |
| S3 | MuJoCo 加外部力/障碍 | F3 | R1/R2 报警，RETREAT→RE_APPROACH |
| S4 | 夹爪闭合后移动物体 | F4 | R5/R6 报警，RE_GRASP |
| S5 | 移动物体/推 EE | F5 | R1/R2/R8 报警，HOLD |
| S6 | `/tf` 加 2cm 偏移 | F6 | R4 报警，HOLD→ABORT |
| S7 | 动作/观测延迟 100–300ms | F7 | R7 报警，HOLD |
| S8 | kill policy server / 改键名 | F8 | 健康检查，ABORT/重连 |

### 6.4 指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 检测延迟 | 故障注入到报警的 chunk 数 | F1/F2/F5/F6 ≤2 chunks；F3/F4 ≤3 |
| FPR | 成功轨迹上误报的 chunk 比例 | <0.5%/chunk；每 10 条成功轨迹 ≤1 次误报 |
| 隔离准确率 | 正确故障类别的比例 | ≥70% |
| 恢复成功率 | 注入故障后完成任务的 trial 比例 | ≥50%（仿真） |
| 恢复时间 | 报警到回到任务轨迹的时间 | ≤3s |
| 安全性 | 碰撞/越界/人接触 | 0 |
| 成功率 | 与 baseline 对比 | +5pp（单任务） |
| 步骤分 | 与 baseline 对比 | 不下降 |

## 8. 竞赛策略

### 8.1 任务组合

- **A 档（19/32，接触密集）**：T01、T05、T09、T10、T12–T14、T17–T20、T23、T25–T29、T31、T32。监控器 + 安全技能全开。
- **B 档（13/32，搬运/分类/变形/动态）**：T02–T04、T06–T08、T11、T15、T16、T21、T22、T24、T30。监控器保守（只开 R1/R7/R8），安全技能只用 HOLD。
- **人为干扰轴（每任务 2/10）**：全任务开 F5 检测；HOLD/RETREAT 优先，不 RE_APPROACH。
- **未见物品/背景/位置**：不依赖物体 ID；R6 视觉 edit 用任务级目标图，不假设物体类别。

### 8.2 单任务通道

用不计分通道做 A/B：

1. **HangCup（T01）**：验证 `H_c`、R1/R2、RE_GRASP、FPR。
2. **PlugInEthernet（T26）**：验证插入卡阻（F3）、RETREAT/RE_APPROACH。
3. **Unlock（T12）**：验证小位移、卡阻、力矩不可得下的位置残差。
4. **Zip Up（T19）**：验证长时序、夹爪滑移、视觉 edit。
5. **人为干扰模拟**：在 HangCup/PlugInEthernet 上移动物体/推手臂，测 F5。

每个任务至少 10 次 baseline + 10 次 monitor（若通道允许，重复到 20–30 次才有统计意义）；记录成功率、步骤分、FPR、检测延迟、恢复时间。

### 8.3 提交节奏

1. **先交 CHUNK-SERVO 基线**：锁定更早提交的 tie-break；确认 32 任务都能跑完。
2. **再交 PRO-SIMPLEX 小范围**：只在 A 档 + 人为干扰开监控；B 档保持基线。
3. **逐步扩大**：G5/G6 通过后，再扩大到更多任务；每次提交只改一个变量。
4. **保留回滚**：如果 G7 回归，回滚到 CHUNK-SERVO；不要为了「创新」牺牲成功率。

### 8.4 端口隔离与并发

```python
services = [PolicyService(port=8765+i, calib=calib, wla=wla_client)
            for i in range(N)]
```

- `PortState` 不共享；`reset()` 清空。
- WLA client 可以共享（只读模型），但请求要带端口 ID，避免响应错配。
- 监控器/技能库是纯函数 + 端口状态；没有全局可变变量。
- 日志按端口分文件；不记录 token。

## 9. 风险与合规

### 9.1 单模型

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| **C1 纯解析** | 监控器/技能库零学习权重；只用几何/统计/物理 | 最低 | **默认** |
| **C2 同模型重规划** | 安全技能 `RE_PLAN` 调用同一 VLA | 低 | 默认 |
| **C3 同 checkpoint 特征** | 用同一 VLA 的 encoder 特征做视觉 edit/OOD | 中；API 不暴露特征 | 仅作可选，需官方确认 |
| **C4 第二模型** | 训练失败分类器/残差策略 | 高；可能违反单模型 | **不做** |

**合规表述**：PRO-SIMPLEX 不引入第二个学习模型；监控器是运行时保障控制器，技能库是确定性轨迹生成器；唯一的学习模型是官方 WLA/VLA。

### 9.2 API 约束

- 没有 chunk 内打断：安全技能最早下一个 chunk 生效；`H_c` 是硬下限。
- 没有 depth/force/tactile：只用 RGB + 本体感知；R5 用夹爪位置+视觉，不用力。
- 腕部无内参：R6 用 SSIM/ORB，不做度量 3D；需要时用头部双目。
- 没有 task ID/goal image：用语言 + 初始图检索成功演示；R6 的目标图从演示库来。
- `action_chunk_size` 固定：静态选 `H_c`；不在 episode 中改。
- 键名/坐标系：适配器必须用单任务通道验证；`gripper_base` vs `gripper_torso` 不能混。

### 9.3 安全

- HOLD/RETREAT 低速、限幅、工作空间约束；RE_APPROACH 只在无人/无 F5 时。
- 诊断出 F5（外部扰动/人为干扰）优先退让；不推人、不加速、不突然动。
- 连续失败 → ABORT；不反复撞同一个障碍。
- 仿真先过 G3/G4；真机先单任务 G5/G6；不直接上 32 任务。

### 9.4 证据与诚实

- 离线实验是合成故障，不是真实失败；检测率不能直接外推。
- 榜单是预览/合成；不能当 SOTA 或失败分布。
- 收益估算是保守区间；G5/G6 不过则按 0 计。
- 不把「检测到」说成「恢复成功」；不把「仿真」说成「真机」。

## 10. 与 CHUNK-SERVO / 相关工作的区别

### 10.1 与 CHUNK-SERVO

| 维度 | CHUNK-SERVO | PRO-SIMPLEX |
|---|---|---|
| 目标 | 最后 3 厘米精度 | 失败后的生存/恢复 |
| 机制 | 30 步计划 + 5 步视觉伺服 | 30 步计划缓存 + 5 步边界监控 + 安全技能 |
| 信号 | 视觉相对位姿/目标图 | 本体感知残差 + 视觉 edit |
| 失败时 | 继续伺服 | 丢弃计划，HOLD/RETREAT/RE_GRASP/RE_PLAN |
| 合规 | 确定性控制器 | 确定性监控器 + 确定性技能 |
| 关系 | 执行层 | 运行时保障层（串联） |

### 10.2 与 failure detection 工作

| 维度 | SAFE/FIPER/FAIL-Detect | Sentinel/ProTracer | CoPRE | 本方案 |
|---|---|---|---|---|
| 学习组件 | 有（MLP/LSTM/RND/flow） | VLM | 无（力矩残差） | **无学习权重** |
| 失败数据 | SAFE 需要；FIPER/FAIL-Detect 不需要 | 不需要 | 不需要 | **不需要** |
| 内部特征 | 需要 | 不需要 | 不需要 | **不需要** |
| 故障范围 | 任务失败 | 任务失败/诊断 | 接触 | **F1–F8** |
| 恢复 | 无 | 无 | 接触退让 | **6 技能 FSM** |
| API 适配 | 需要 embedding/多采样 | 需要 VLM | 需要力矩 | **只用 API 可见信号** |
| 延迟 | 中/高 | 高 | 低 | **1 chunk（167ms）** |

### 10.3 与 Simplex

Black-Box Simplex 证明「AC 不可信、BC 可信、DM 切换」可以保证安全；本方案把 AC 换成 VLA，把 BC 换成安全技能库，把 DM 换成 chunk-boundary 监控器。区别是：VLA 的动作空间是 EE/关节 chunk，BC 不是完整策略而是短时技能；安全保证从「形式化可达集」降级为「工程约束 + 实验门」，这是本方案要诚实说明的边界。
