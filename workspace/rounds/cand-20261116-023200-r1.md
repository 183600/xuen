# 第 10 轮（本轮灵感：「技能组合」×「技术路线图」）

> **基线**：第 9 轮 MetricVoiceGauge-ACMD（定义 532–539；引理 82–86；实验 E551–E570）。
> 本轮纪律：**组合闭合 + 证据门控 + 路线单调**。v9 解决了“模块怎么接线、失效怎么办”，但留下两个新债：**组合债**（单模块证书不蕴含多技能组合证书，接口误差、资源叠加与交互耦合可让两个安全技能组合出危险行为）与**证据债**（ID 只回答“谁值得算力”，没回答“谁有资格真正驱动执行器、还缺什么证据”）。本轮以 P13–P15 治理：技能组合必须闭合于证书，执行授权必须门控于成熟度证据，路线图只能改变离线证据计划、不能改变运行时安全域。

## 0. 直觉与动机

**灵感 1（技能组合 → 交互感知的技能代数）**
直觉：v9 把“组合”理解为端口接线与中立元注入，像是在做函数复合；但机器人技能是带前置条件、后置条件、不变量、资源包络与失败时间的闭环策略。两个各自被认证的技能串起来，前一技能的后置状态可能只落在后一技能前置条件的边界附近；执行器饱和、接触、感知延迟会让误差跨边界传播；资源预算也会相加。因此“各自安全 ⇒ 组合安全”是**假的**。核心创新：**技能契约组合器（SkillContractComposer, SCC）**。它把技能写成契约，把组合定义为**部分幺半群**上的运算：只有接口统一、交互余量非负、资源和不超包络、不变量交非空时才可组合；组合证书的强度**单调不增**（不会比成分更强）。若组合不可认证，就执行“最大已认证前缀”后安全停驻，或退回单技能 / v9 分块模式——退化目标明确，不是行为漂移。

**灵感 2（技术路线图 → 证据门控的能力路线）**
直觉：一个系统有 16+ 个 IP，真正的问题不是“再发明一个模块”，而是“哪项能力现在有资格上线、下一步该补哪块证据、哪些能力只是论文里的能力”。技术路线图的本质是**带门控的阶段化能力成熟**。核心创新：**路线图门（RoadmapGate, RG）**与**路线规划器（RoadmapPlanner, RP）**。能力图 G 的节点是技能/模块/组合技能，边是依赖与组合；每个节点有成熟度 μ 与证据包 B。运行时执行授权不是由贡献 c_m 决定，而是由 μ 决定的**授权域 Dom_μ**：低成熟度只能影子运行（只记录不驱动），高成熟度才可在其已认证前置域内执行。路线图规划器只在离线分配实验预算、选择下一批证据采集；它不能抬高硬地板、不能扩大认证域。于是规划器犯错只会损失能力，不会直接造成不安全——**规划/执行单向分离**。

**灵感 3（二者耦合 → 组合证据不可继承）**
直觉：最危险的是把技能组合当成“证据的加法”：σ₁ 有 500 次成功、σ₂ 有 500 次成功，就认为 σ₁;σ₂ 有 1000 次成功。错。组合引入了一个新的随机对象——**接口分布**。两个高置信度成分可以在接口处出现低置信度的组合，尤其是接触切换、抓取交接、窄通道换向。核心创新：**组合证据探针（CompositionEvidenceProbe, CEP）**：每条组合边必须有自己的交互证据键 (σ₁,σ₂,接口分布)，路线图必须为它预留实验预算；缺证据的边一律不可认证。这把“技能组合”和“技术路线图”真正缝在一起：组合产生新的路线图节点，路线图必须为组合支付证据成本。

## 1. 研究问题（轮次升级版）

- **Q1（组合闭合性）**：在何种接口契约与扰动模型下，两个分别满足 (Pre, Post, Inv, R, α) 的技能，其顺序/并行组合仍满足可证明的证书？接口残差如何度量，组合证书的强度上界是什么？部分幺半群的结合律与单位元在何种意义下成立？
- **Q2（证据门控与授权）**：如何定义成熟度等级 μ、证据要求 Ev_ℓ 与授权域 Dom_μ，使运行时执行授权对证据单调、对贡献/流行度不敏感？如何保证证据陈旧、域偏移与路线图规划错误只收缩能力，而不扩大危险动作集？
- **Q3（组合证据与退化）**：如何形式化“证据不可继承”，使缺交互证据的组合无法被错误晋升？SCC/RG/RP 失效时如何逐级退回 v9 的 AC/MW/ID 与 v8/v7，且可观测行为可审计？

## 2. 设计原则（在 P10–P12 基础上新增 P13–P15）

**P13 组合闭合律（Composition Closure, SCC）**
只有通过组合门 Ω_comp 的技能序列才可执行。Ω_comp(σ₁;σ₂) 要求：(i) 接口统一：Post_{σ₁} 在鲁棒距离下落入 Pre_{σ₂}，带符号余量 m ≥ δ_int；(ii) 资源闭合：R_{σ₁}+R_{σ₂} ≤ B_skill；(iii) 不变量闭合：Inv_{σ₁}∩Inv_{σ₂}∩H_{12} ≠ ∅，H_{12} 为交接不变量；(iv) 交互证据存在且新鲜。组合证书强度满足 Cert(σ₁;σ₂) ⊑ Cert(σ₁) ⊓ Cert(σ₂)（保守单调）；不可闭合时执行最大已认证前缀，再安全停驻，绝不“边跑边补证”。

**P14 证据门控律（Evidence-Gated Authority, RG）**
执行授权是成熟度证据的函数，而不是贡献、置信度叙事或历史名气的函数。μ(v) < μ_deploy ⇒ 影子模式（只推理、只记录、不驱动）；μ(v) ≥ μ_deploy 才获得 Dom_μ(v) ⊆ Pre_v 的授权域。晋升需过证据门（置信下界、样本量、覆盖集、形式义务、零严重违规）；降级在违规/证据过期时**立即**发生。贡献 c_m 只影响算力分配（v9 ID），绝不影响执行授权。

**P15 路线单调分离律（Roadmap Monotonicity & Separation, RP）**
路线图规划器只作用于离线元数据：实验排期、证据采集、影子/授权建议。它不能修改硬地板、安全证书、P13 组合门或 P14 授权域。证据增加只能使 μ 不减；证据撤回/过期只能使 Dom_μ 收缩。组合节点必须携带独立交互证据，禁止从成分继承。由此规划器的任意错误是**能力侧单边**的：最多让系统更保守，不会直接产生不安全动作。

## 3. 与基线的接口（如何退化）

- SCC 无可行组合 ⇒ 执行最大已认证前缀，再安全停驻；若前缀为空 ⇒ 单技能执行，按 v9 AC 的 K_eff 生成动作块（组合粒度退化为 v9 决策粒度）；
- CEP 交互证据缺失/过期 ⇒ 该组合边不可认证（属 SCC Level-1），绝不晋升为组合技能；
- RG 证据系统不可用 ⇒ v9 继承模块沿“祖父条款”保留 v9 授权，新技能一律影子；系统行为等价 v9；
- RP 失效 ⇒ 路线图冻结为静态表（不做实验规划），运行时不调用；因 P15，安全语义不变；
- v9 的 AC/MW/ID 任一失效 ⇒ 沿 v9 五级链退回 v8；
- 全部失效 ⇒ 完整退回 MetricVoiceGauge-OTL-GC-ER v7，再退回 v6。

> **与 v9 引理 83 的关系**：v9 证明“模块失效 ⇒ 中立元 ⇒ 逐位等价 v8”。本轮不否定它，而是指出它只覆盖**单模块端口层**，不覆盖**技能边界层**：即使每个端口都逐位等价，两个技能在交接处仍可能因后置误差、资源叠加和接触耦合产生新风险。因此 P13 在 v9 之上增加“组合必须重新认证”，而不是把 v9 的组合语义当成免费性质。

## 4. 预期贡献

1. **交互感知的技能组合演算**：技能契约、接口残差、资源闭合、组合证书强度单调性与最大认证前缀回退，给出“组合不免费”的可证明版本；
2. **证据门控的能力路线图**：成熟度/证据/授权域三层分离，LCB 晋升门与即时降级，规划器错误单边化；
3. **组合证据不可继承**：把交互证据作为一等公民，路线图必须为组合边支付证据预算；把 v9 的“贡献归因”与“授权归因”明确分开；
4. **实验 E571–E590**：组合证书可靠性、接口扰动、资源叠加、证据门控校准、路线规划收益、影子到全权过渡、组合×分块/契约/蒸馏耦合与端到端竞赛仿真。

## 5. 本轮最大风险

**一句话**：整套组合安全性依赖接口模型把跨技能耦合（接触、饱和、时延、未建模扰动）全部收进残差 δ_int；一旦某个耦合被低估，两个各自“高置信”的技能就能在交接处组合出证书之外的行为，而路线图的证据门还可能因组合节点被错误晋升而放大这种虚假置信。

# 第 10 轮产物 · 创新点清单 v10：**MetricVoiceGauge-SCRT**（Skill-Composition Calculus & Roadmap-gated Trust）

> 背景：第 9 轮 MetricVoiceGauge-ACMD（定义 532–539；引理 82–86；实验 E551–E570）。
> 本轮灵感：「技能组合」×「技术路线图」。
> **继承纪律**：MetricVoiceGauge 九不变式与 v9 的 AC / MW / ID 全部保留；本轮新增组件一律为**可选增强**。新增能力只在通过组合门与证据门时生效，任一环节不可用即退回 v9 的单技能/分块语义，再沿 v9 五级链退回 v8/v7，而非行为漂移。与 v9 的最大区别：v9 保证“端口失效 ⇒ 中立元 ⇒ 等价”，本轮进一步要求“**技能边界必须重新认证**”，因为组合不是免费的。

## 2. 形式化定义

**定义 540（技能契约 SkillContract）**
*直觉*：技能不是“一个动作”，而是一段带承诺的闭环行为：在什么状态下可以启动、结束后保证落在哪里、全程不能碰什么、最多花多少资源、失败概率多大。
*定义*：技能 σ=(Pre_σ, Post_σ, Inv_σ, π_σ, R_σ, α_σ, W_σ)，其中 Pre_σ, Post_σ, Inv_σ ⊆ X 为状态区域，π_σ: X→U 为闭环策略，R_σ=(T_σ,E_σ,A_σ) 为时间/能量/执行器权限包络，α_σ∈[0,1]，W_σ 为认证扰动集。语义：∀x∈Pre_σ，∀w∈W_σ，执行 σ 的轨迹满足
```
∀t: x_t ∈ Inv_σ,   x_end ∈ Post_σ,   P(success) ≥ 1 − α_σ,   cost(σ) ≤ R_σ.
```
v9 的 ActionChunk ζ_t 是 σ 的一个特例：Pre 为当前可信状态集，Post 为块末状态集，Inv 为块内证书约束，R 为块预算，α 由 β 与前向模型误差换算。

**定义 541（接口统一度 InterfaceUnification）**
*直觉*：两个技能能不能串，不只看“结束状态在不在下一个的前置条件里”，还要看离边界有多远、允许的初始误差有多大、资源还剩多少。
*定义*：
```
m(σ₁,σ₂)     = dist_robust(Post_{σ₁}, X \ Pre_{σ₂}) − δ_int
r_int(σ₁,σ₂) = e_pre^max(σ₂) − e_end^max(σ₁) − δ_int
ΔR(σ₁,σ₂)    = B_skill − R_{σ₁} − R_{σ₂}
s_int        = min(m, r_int, ΔR)
```
其中 dist_robust 在 W_{σ₁}∪W_{σ₂} 与状态估计误差下取下确界。Ω_comp(σ₁;σ₂) 成立 ⇔ s_int ≥ 0 且 Inv_{σ₁}∩Inv_{σ₂}∩H_{12} ≠ ∅ 且交互证据 k(σ₁;σ₂) 新鲜。H_{12} 为交接不变量（例如“交接期间物体必须被至少一只手握住”）。

**定义 542（顺序组合与组合证书）**
*直觉*：组合的失败概率至少是三者之和——前一段失败、后一段失败、接口失败；资源相加；不变量取交；证书只会变弱，不会变强。
*定义*：若 Ω_comp(σ₁;σ₂) 成立，则
```
σ₁;σ₂ = (Pre_{σ₁}, Post_{σ₂}, Inv_{σ₁}∩Inv_{σ₂}∩H_{12},
         π_{σ₂}∘π_{σ₁}, R_{σ₁}+R_{σ₂},
         min(1, α_{σ₁}+α_{σ₂}+α_int), W_{σ₁}∪W_{σ₂})
```
其中 α_int ≥ P(接口违约) 由 CEP 标定。组合证书
```
Cert(σ₁;σ₂) = (Pre_{σ₁}, Post_{σ₂}, Inv_{σ₁}∩Inv_{σ₂}∩H_{12},
                R_{σ₁}+R_{σ₂}, min(1,α_{σ₁}+α_{σ₂}+α_int),
                k(σ₁;σ₂)).
```
证书强度偏序：C₁ ⊑ C₂ ⇔ Pre₁ ⊆ Pre₂ ∧ Post₁ ⊇ Post₂ ∧ Inv₁ ⊆ Inv₂ ∧ R₁ ≥ R₂ ∧ α₁ ≥ α₂。由此立即有
```
Cert(σ₁;σ₂) ⊑ Cert(σ₁) ⊓ Cert(σ₂),
```
即组合不会凭空增强证书。

**定义 543（并行组合 ParallelComposition）**
*直觉*：并行不是“两个技能各跑各的”，而是“彼此不能破坏对方的不变量，且资源不能打架”。
*定义*：σ₁∥σ₂ 可认证 ⇔ R_{σ₁}∩R_{σ₂}=∅（或显式分配），且存在耦合界 γ_c 使
```
∀t: dist(x_t, Inv_{σ₁}) ≤ γ_c ⇒ x_t ∈ Inv_{σ₂},  反向同理；
Cert(σ₁∥σ₂) = (Pre_{σ₁}∩Pre_{σ₂}, Post_{σ₁}∩Post_{σ₂},
                Inv_{σ₁}∩Inv_{σ₂}, R_{σ₁}∪R_{σ₂},
                min(1,α_{σ₁}+α_{σ₂}+α_c), (k_{σ₁},k_{σ₂},k_c)).
```
并行组合不假设可交换；仲裁顺序必须在契约中显式声明。

**定义 544（最大已认证前缀 MaximalCertifiedPrefix）**
*直觉*：组合不了时，不要“赌一把把整条路线跑完”，而是跑到最后一个确定安全的技能边界，然后停。
*定义*：对路线 (σ₁,…,σ_k)，令 P_j=σ₁;…;σ_j。若 P_j 逐段满足 Ω_comp，则 j*=max{j: P_j 可认证}。执行器执行 P_{j*}，随后进入安全停驻；若 j*=0，则只执行当前最安全的单技能，并按 v9 AC 生成其动作块。该定义保证“不可认证的后缀永不执行”。

**定义 545（能力图 CapabilityGraph）**
*直觉*：技能、模块、组合技能都是能力节点；依赖和组合是两类不同的边；组合节点是“新节点”，不是一个免费别名。
*定义*：G=(V, E_dep ∪ E_comp)。V 包含模块节点、原子技能节点与组合技能节点；E_dep 表示“要先具备”；E_comp 表示“可组合”，每条 e=(σ₁,σ₂)∈E_comp 携带接口分布 D_int(e) 与组合证据键 k(e)=(id(σ₁),id(σ₂),D_int(e))。组合节点 v=σ₁;σ₂ 的证据键为 k(e)，不是 k(σ₁)∪k(σ₂)。

**定义 546（证据包与成熟度 EvidenceBundle & Maturity）**
*直觉*：成熟度不是“用了多久”，而是“在目标分布上积累了多少可复核的证据”。证据必须能被置信下界和覆盖集检查。
*定义*：B_v={(n_i,k_i,δ_i,D_i)} 加形式义务集合 O_v。对二项成功事件，用 Clopper–Pearson 下界 LCB(k,n,δ)。成熟度
```
μ(v) = max{ ℓ ∈ {0,1,2,3,4} :
            LCB(k,n,δ) ≥ 1−α_ℓ
          ∧ n ≥ N_min(ℓ)
          ∧ coverage(B_v) ⊇ C_ℓ
          ∧ critical_violations(B_v)=0
          ∧ O_ℓ 已全部解除 }
```
若证据超期（age > T_evid）或 Δ_dom ≥ τ_dom，则 μ(v)←max(0,μ(v)−1)，直到复证完成。

**定义 547（授权域 AuthorityDomain）**
*直觉*：证据不足不是“少给一点动作权重”，而是“根本不允许在这个状态子集之外驱动执行器”；用集合授权比用动作插值更容易证明安全。
*定义*：
```
Dom_0(v)=∅                                   (shadow，只推理不驱动)
Dom_1(v)⊆Pre_v                               (suggest，需人/守卫确认)
Dom_2(v)⊆Pre_v                               (supervised，安全监控可否决)
Dom_3(v)=Pre_v ∩ Inv_route                   (certified)
Dom_4(v)=Dom_3(v)                            (full，允许承担整条认证路线)
Dom_0 ⊆ Dom_1 ⊆ Dom_2 ⊆ Dom_3 = Dom_4.
```
运行时：技能 v 可在状态 x 驱动执行器 ⇔ x∈Dom_{μ(v)}(v) 且所在组合边的门通过。若安全集非凸，禁止用动作凸组合“部分授权”；授权是门，不是权重。

**定义 548（证据债 EvidenceDebt）**
*直觉*：路线图不是愿望清单，而是“还缺多少证据”的账本；安全关键节点的债先还。
*定义*：D(v,ℓ)=max(0, Ev_ℓ−B_v)（逐分量），D_int(e)=max(0, Ev_int−B_e)。优先级
```
prio(v,ℓ) = 1{φ^safety(v)} · D(v,ℓ) + λ · IG(v,ℓ)/cost(v,ℓ),
```
其中 IG 为期望信息增益，λ 为性能权重。安全关键证据债的优先级严格高于性能证据债。

**定义 549（认证路线 CertifiedRoute / 技术路线）**
*直觉*：“技术路线”在这里不是甘特图，而是一条每条边都有独立组合证书、每个节点都过授权门的能力路径。
*定义*：ℛ=(v₀,e₁,v₁,…,e_k,v_k)，e_i=(v_{i−1},v_i)∈E_comp 且 Cert(e_i) 非空、证据新鲜。路线证书
```
Cert(ℛ) = Cert(e₁) ⊓ Cert(e₂) ⊓ … ⊓ Cert(e_k),
```
并要求 Σ_i R_{e_i} ≤ B_task、∀i: μ(v_i) ≥ μ_deploy。ℛ 可执行 ⇔ Cert(ℛ) 非空且所有边门与节点门同时通过。

**定义 550（路线图计划 RoadmapPlan）**
*直觉*：规划器只决定“先测什么、先补哪条证据”，不决定“现在允许多危险”。
*定义*：π_road = ((v₁,e₁),…,(v_m,e_m)) 为实验/证据采集序列，带成本 cost_i 与期望证据增益 IG_i。规划目标
```
max  Σ_i IG_i · x_i
s.t. Σ_i cost_i · x_i ≤ B_evidence,
     x_i ∈ {0,1},
     安全关键证据债优先满足。
```
π_road 只写 B_v、μ(v) 的**建议**与影子排期；运行时授权由 RG 依据证据独立计算，规划器无写权限。

**定义 551（组合证据键与不可继承 EvidenceNonInheritance）**
*直觉*：两个技能各自考了 100 分，不代表“它们交接”考了 100 分；交接是一门新科目。
*定义*：组合边 e=(σ₁,σ₂) 的证据键为 k(e)=(id(σ₁),id(σ₂),D_int(e))。其证据包 B_e 必须在 D_int(e) 上独立采样；晋升组合节点 v=σ₁;σ₂ 时只查 B_e，禁止用 B_{σ₁}∪B_{σ₂} 代替。缺 B_e ⇒ 边不可认证，节点最多停留在 μ=0（影子）。

**定义 552（授权阶梯与影子模式 AuthorityLadder）**
*直觉*：让新技能先在“只看不做”的模式下积累证据，再逐级放权；一旦违规，立刻收回。
*定义*：mode(v)=shadow/suggest/supervised/certified/full 对应 μ=0/1/2/3/4。迁移规则：晋升只能经定义 546 的证据门；降级在以下任一条件成立时**下一控制周期**生效：严重安全违规、证据过期、Δ_dom ≥ τ_dom、组合边证据失效。降级不可被路线图计划覆盖。

**定义 553（组合感知退化映射 CompositionAwareDegradation）**
*直觉*：不同层的失败要退回不同的层，不能一律“回退到 v8”了事。
*定义*：退化映射
```
SCC 无组合 → 最大认证前缀 / 单技能 + v9 AC (Level-1)
CEP 缺边证据 → 该边不可认证，绝不晋升 (Level-1)
RG 证据系统失效 → v9 继承模块祖父授权，新技能影子 (Level-2)
RP 失效 → 静态路线图，运行时不变 (Level-3)
v9 AC/MW/ID 失效 → v9 五级链 → v8 (Level-4)
全部失效 → v7 → v6 (Level-5)
```
映射要求日志可审计：每个退化决策记录触发条件、当前 μ、当前授权域与最大认证前缀长度。

# ---------- IP-357 SkillContractComposer：技能契约组合器 ----------
@dataclass
class SkillContract:
    name: str
    pre: Region; post: Region; inv: Region
    policy: Callable
    R: ResourceEnvelope          # (time, energy, authority)
    alpha: float                 # failure prob upper bound
    W: DisturbanceSet
    e_end_max: float             # worst-case terminal error
    e_pre_max: float             # allowed initial error
    evidence_key: tuple = ()

@dataclass
class Cert:
    pre: Region; post: Region; inv: Region
    R: ResourceEnvelope
    alpha: float
    key: tuple
    def __le__(self, other):     # C1 <= C2 表示 C1 不强于 C2（定义 542）
        return (self.pre <= other.pre and self.post >= other.post
                and self.inv <= other.inv and self.R >= other.R
                and self.alpha >= other.alpha)

class SkillContractComposer:
    def __init__(self, cep, delta_int=0.02, B_skill=None):
        self.cep, self.delta_int, self.B_skill = cep, delta_int, B_skill

    def interface_slack(self, a, b):
        m = robust_distance(a.post, complement(b.pre), a.W | b.W) - self.delta_int
        r = b.e_pre_max - a.e_end_max - self.delta_int
        dR = (self.B_skill - a.R - b.R).min_slack()
        return min(m, r, dR)

    def admissible(self, a, b):
        if self.interface_slack(a, b) < 0:            return False
        if (a.inv & b.inv & handoff(a, b)).is_empty(): return False
        if not self.cep.fresh((a.name, b.name)):       return False
        return True

    def compose(self, a, b):
        if not self.admissible(a, b):
            return None                                # 不组合，调用方执行前缀
        alpha_int = self.cep.upper_bound((a.name, b.name))
        cert = Cert(
            pre=a.pre, post=b.post,
            inv=a.inv & b.inv & handoff(a, b),
            R=a.R + b.R,
            alpha=min(1.0, a.alpha + b.alpha + alpha_int),
            key=(a.name, b.name, self.cep.interface_dist(a, b)))
        return ComposedSkill(a, b, cert)

    def maximal_prefix(self, route):
        if not route: return None
        acc = route[0]
        for nxt in route[1:]:
            comp = self.compose(acc, nxt)
            if comp is None: break
            acc = comp
        return acc


# ---------- IP-358 CompositionEvidenceProbe：组合证据探针 ----------
class CompositionEvidenceProbe:
    def __init__(self, alpha_int=0.01, N_int=200, T_evid=1800.0):
        self.alpha_int, self.N_int, self.T_evid = alpha_int, N_int, T_evid
        self.bundles = {}

    def run(self, a, b, interface_dist, simulator):
        states = interface_dist.sample(self.N_int)
        successes, violations = 0, 0
        for x in states:
            trace = simulator.rollout(a, b, x)        # 只测交接，不测全任务
            if trace.critical_violation: violations += 1
            elif trace.success:          successes += 1
        lcb = clopper_pearson_lower(successes, self.N_int, 0.05)
        self.bundles[(a.name, b.name)] = EvidenceBundle(
            n=self.N_int, k=successes, lcb=lcb,
            coverage=interface_dist.coverage, violations=violations,
            t_stamp=now())
        return self.bundles[(a.name, b.name)]

    def fresh(self, key):
        b = self.bundles.get(key)
        return b is not None and (now() - b.t_stamp) <= self.T_evid

    def upper_bound(self, key):
        b = self.bundles[key]
        return 1.0 - b.lcb                        # 保守失败上界


# ---------- IP-359 RoadmapGate：路线图门 ----------
class RoadmapGate:
    LEVELS = range(5)
    ALPHA   = [1.0, 0.20, 0.10, 0.05, 0.02]
    N_MIN   = [0,   50,   150,  400,  1000]
    COVER   = [set(), {"nominal"}, {"nominal","perturbed"},
               {"nominal","perturbed","edge"}, "full"]

    def __init__(self, domain_shift_fn):
        self.domain_shift = domain_shift_fn
        self.mu = {}

    def promote(self, v, level, B):
        return (B.n >= self.N_MIN[level]
                and B.lcb >= 1 - self.ALPHA[level]
                and self.COVER[level] <= B.coverage
                and B.violations == 0
                and B.formal_ok)

    def update(self, v, B, now):
        mu = 0
        for level in self.LEVELS:
            if self.promote(v, level, B): mu = level
        if B.stale(now) or self.domain_shift() >= TAU_DOM:
            mu = max(0, mu - 1)                   # 证据过期/域漂移 → 降级
        self.mu[v.name] = mu
        return mu

    def authority_domain(self, v):
        mu = self.mu.get(v.name, 0)
        return AUTHORITY_SETS[mu] & v.pre          # Dom_mu ⊆ Pre

    def gate(self, v, x, edge_ok=True):
        return edge_ok and x in self.authority_domain(v)


# ---------- IP-360 RoadmapPlanner：路线规划器 ----------
class RoadmapPlanner:
    def __init__(self, gate, composer, budget):
        self.gate, self.composer, self.budget = gate, composer, budget

    def evidence_debt(self, v):
        return {lvl: max(0, self.gate.N_MIN[lvl] - v.B.n)
                for lvl in RoadmapGate.LEVELS}

    def plan(self, G, budget):
        # 安全关键证据债优先；其余按 IG/cost 贪心（不做运行时授权）
        items = []
        for v in G.nodes:
            for lvl, debt in self.evidence_debt(v).items():
                if debt > 0:
                    items.append(Experiment(v, lvl, debt, cost_of(v, lvl)))
        items.sort(key=lambda e: (not e.v.safety_critical,
                                  -e.info_gain_per_cost()))
        chosen, spent = [], 0.0
        for e in items:
            if spent + e.cost <= budget:
                chosen.append(e); spent += e.cost
        return RoadmapPlan(chosen, spent)

    def certified_route(self, G, start, goal):
        # 只走组合证书非空且证据新鲜的边；边权 = 组合失败的保守代价
        return shortest_path(G, start, goal,
                             edge_ok=lambda e: self.composer.admissible(*e)
                                               and self.composer.cep.fresh(e.key))


# ---------- IP-361 CertifiedRouteExecutor：认证路线执行器 ----------
class CertifiedRouteExecutor:
    def __init__(self, composer, gate, v9_chunker, safe_stop):
        self.composer, self.gate = composer, gate
        self.chunker, self.safe_stop = v9_chunker, safe_stop

    def step(self, route, x, k_exec):
        edge = route.current_edge
        # 1) 节点授权门
        if not self.gate.gate(edge.src, x):
            return self.fallback(route, x)
        # 2) 组合边门（含在线接口余量复核）
        if not self.composer.admissible(edge.src, edge.dst) or \
           self.composer.interface_slack(edge.src, edge.dst) < 0:
            return self.fallback(route, x)
        # 3) 技能内部动作生成仍由 v9 AC 负责（分块证书不丢）
        return self.chunker.step(x, k_exec)

    def fallback(self, route, x):
        prefix = self.composer.maximal_prefix(route.skills_so_far)
        if prefix is None:
            return self.safe_stop(x)                  # j*=0：安全停驻
        return self.safe_stop_after(prefix, x)        # 执行前缀后停驻

## 4. 推导

**引理 87（组合可靠性 / Composition Soundness）**
设 σ₁、σ₂ 分别满足定义 540 的证书，且 Ω_comp(σ₁;σ₂) 成立，接口违约概率 ≤ α_int。则 σ₁;σ₂ 满足 Pre_{σ₁}、Post_{σ₂}、全程 Inv_{σ₁}∩Inv_{σ₂}∩H_{12}，失败概率 ≤ min(1, α_{σ₁}+α_{σ₂}+α_int)，资源 ≤ R_{σ₁}+R_{σ₂}。
**证明**：把组合失败事件划分为 E₁（σ₁ 在其域内失败）、E₂（σ₂ 在其域内失败）、E_int（交接违约）。由定义 540，P(E₁)≤α₁、P(E₂)≤α₂；由定义 541 与 CEP，P(E_int)≤α_int。三者并集的上界为 α₁+α₂+α_int。轨迹拼接：σ₁ 终止于 Post_{σ₁}，接口统一保证 Post_{σ₁}⊆Pre_{σ₂}（鲁棒意义下），故 σ₂ 可启动并终止于 Post_{σ₂}；全程不变量取交。资源由定义 542 相加且 Ω_comp 保证不超 B_skill。∎

**引理 88（组合不免费 / 交互项必要性）**
不存在只依赖成分证书 (Pre,Post,Inv,R,α) 而不依赖接口项 (m,r_int,α_int) 的可靠组合规则；对任意此类规则，存在两个各自满足证书的技能，其组合违反不变量。
**证明（构造）**：取一个“抓取—搬运”技能 σ₁ 与“放置”技能 σ₂。σ₁ 的证书只承诺终端位置误差 ≤ e_end；σ₂ 的证书只承诺在初始速度 ≤ v₀ 时安全。若 σ₁ 在接近边界时执行器饱和，终端速度可为 v₁>v₀，而位置仍满足 Post_{σ₁}。仅看 (Pre,Post,Inv,R,α) 的规则会接受 σ₁;σ₂；但实际交接速度超限，σ₂ 的停车不变式被破坏。该反例说明必须显式引入 r_int（速度/误差/接触状态）与 α_int。∎

**引理 89（部分幺半群与证书单调）**
在接口兼容的技能类上，顺序组合 ; 满足结合律（在接口等价意义下）；恒等技能 id=(X,X,X,no-op,0,0,∅) 是左右单位元；组合证书单调不增：Cert(σ₁;σ₂) ⊑ Cert(σ₁) ⊓ Cert(σ₂)。组合一般不可交换。
**证明**：结合律由轨迹拼接的结合性与区域交的结合性直接得到；接口等价吸收顺序差异。单位元显然。单调性逐分量由 R₁+R₂≥R₁、α₁+α₂+α_int≥α₁、以及组合不变量取交、后置区域取后者得到。不可交换性由抓取/放置反例给出。∎

**引理 90（授权域安全性）**
若 x∈Dom_{μ(v)}(v)、μ(v)≥μ_deploy、且组合边门通过，则执行 v 的一个控制周期仍使状态处于 Inv_v 且资源不超 R_v；若任一条件不成立，门拒绝执行并触发回退。
**证明**：由定义 547，Dom_μ⊆Pre_v；定义 540 给出在 Pre_v 内执行保持 Inv_v 与资源包络。组合边门通过时，引理 87 给出交接后的不变量；边门失败时 CRE 截断到最大认证前缀，仍由引理 87 保证前缀安全，随后安全停驻。∎

**引理 91（规划/执行分离 / 规划错误单边）**
对任意路线图计划 π_road，运行时被允许的动作集合 ⊆ ⋃_{v: μ(v)≥μ_deploy} Dom_{μ(v)}；π_road 只能通过产生新证据改变 μ，不能直接写 μ 或 Dom。因此规划器的任意错误只会使被允许集合收缩或不变，不会扩大危险动作集。
**证明**：由 P15，π_road 的输出仅为 B_v 的采集建议与影子排期；μ 由 RG 按定义 546 依据 B_v 重新计算；Dom 由定义 547 由 μ 与 Pre 决定。π_road 无写权限。RG 的晋升谓词对证据单调（增加证据不会降低 LCB），降级条件（违规/过期/域漂移）只会降低 μ。故允许集合对规划器错误是单边保守的。∎

**引理 92（组合证据不可继承）**
存在技能 σ₁、σ₂，其在各自分布上的成功概率 LCB 均 ≥ 1−α，但组合边 e=(σ₁,σ₂) 在接口分布 D_int 上的成功 LCB 可任意低；因此 B_e 不是 B_{σ₁} 与 B_{σ₂} 的函数。
**证明（构造）**：令 σ₁ 与 σ₂ 各自在“对方已把物体交给本方”的假设下训练与测试，二者单独测试的成功率都高；令 D_int 集中在“双方同时松手”的交接状态。在该状态上 σ₁;σ₂ 必失败，而两个成分的单独测试分布几乎不覆盖该状态。故组合证据必须独立测量。∎

**引理 93（与 v9 分块执行兼容 / 退化等价）**
当 SCC 无可行组合（j*=1）时，CRE 将单个技能的动作生成委托给 v9 AC，输出动作序列与 v9 在该技能上的分块执行逐周期一致；当组合边存在但证据缺失时，边被拒绝而非静默执行。故 v10 的组合层失效严格退回 v9 语义，且不会把“未认证组合”当作 v9 单技能执行。
**证明**：CRE.step 在 j*=1 时直接调用 v9_chunker.step，状态、K_eff、证书与 v9 相同；组合边门在调用前显式检查 CEP.fresh，缺证据返回 fallback 而非 chunker。由 v9 的引理 82–86，单技能路径保持原语义。∎

## 8. 本轮最大风险

**一句话**：整套组合安全性依赖接口模型把跨技能耦合（接触、饱和、时延、未建模扰动）全部收进残差 δ_int；一旦某个耦合被低估，两个各自“高置信”的技能就能在交接处组合出证书之外的行为，而路线图的证据门还可能因组合节点被错误晋升而放大这种虚假置信。
