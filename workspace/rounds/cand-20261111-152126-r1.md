# 第 55 轮（承接第 54 轮 v31 GroundEdge-GenSim+++；灵感循环第 6 轮；本轮灵感：「伦理审查」×「用户共创」）

> 第 54 轮把技能组合推进到「动作剖面 α_S + 鲁棒性谱 ρ + 云边映射 γ_ce」的联合证书 `J`。但 `J` 只回答「机器人**能不能**做」，从未回答「谁**授权**它做、为谁做、做多久、可否反悔」。本轮引入 **伦理审查** 与 **用户共创**，不是给证书加一个伦理分数，而是给整个证书栈加一个**治理层**。核心矛盾：H22：技术 sound 的动作在伦理上可能不可接受，且这种不可接受性是**情境与利益相关者索引**的，无法用单一标量 θ_eth 表达；H23：把用户共创当作一次性需求采集，会把「用户同意」固化成不可撤回的静态假设，产生**同意债与伦理洗白（ethics washing）**。

## 0. 直觉与动机

**灵感 1（伦理审查不是门禁，而是证书的发行方）**
直觉：IRB（伦理审查委员会）在人类受试研究中不是实验参数，而是**授权机构**。同理，机器人的伦理审查不应写成 `J` 里的又一项指标，而应决定 `J` 在什么情境、对哪些人、在多长时间内**有效**。技术证书回答「真」，伦理审查回答「可」。二者是**不同范畴**：ρ 有物理参照，ε 有社会参照；把 ε 压成一个数塞进 `J`，是范畴错误的开端。所以本轮的第一原则是：**伦理审查居于证书之上，而非之内。**

**灵感 2（用户共创 = 共同定义可接受动作空间，而非采集需求）**
直觉：第 54 轮的动作空间 `A_tech` 由机器人能力给定；伦理上真正可部署的是 `A_deploy(c) = A_tech(c) ∩ E_eth(c)`，其中 `E_eth(c)` 是利益相关者共同定义的**伦理包络**。用户不是在给工程师「提需求」，而是在**共同划定动作空间的边界并共同署名证据**。这把「用户」从数据来源升级为证书的**共同作者**：他们既能提供工程师想不到的边界场景（提升技术覆盖），也能行使否决与撤回（保留治理权力）。因此共创不是伦理成本，而可能是**覆盖与合法性的双赢**——这是本轮可被实验检验的正面假设。

**灵感 3（异质性 → 单一伦理分数在数学上就不 sound）**
直觉：不同用户对「机器人在我身边多快移动」的接受度不同，且没有共同货币可换算。社会选择理论早已指出：在 |U|≥3、偏好不受限时，不存在同时满足一致性、无关备选独立性与非独裁的标量聚合（Arrow）。所以任何 `θ_eth` 要么是独裁的（某人的偏好冒充全体），要么是可被操纵的（阈值套利）。正确做法不是追求一个「伦理总分」，而是**保留异议**：证书携带可接受度向量与偏序，部署只在**否决安全集**内进行，分歧显式升级而非被平均掉。

**灵感 4（同意是带范围、期限、可撤回的令牌）**
直觉：同意不是布尔值，而是 `(谁, 对哪些动作/情境, 多久, 可撤回)` 的**能力令牌**。机器人一旦部署，情境会变（新路人、新地点、新任务、能力漂移），旧同意会**静默过期**。因此需要类似证书吊销列表的 **CRL-E**：同意可撤回、可过期、可被审计；边端在执行前必须检查吊销状态与新鲜度证明。把「已获同意」当作永久事实，就是**同意债**。

**灵感 5（伦理审查闭环 = 部署-异议-撤回-再同意）**
直觉：第 54 轮有「云规划-边校验-反向解释-重剖分」闭环；本轮叠加一条**社会闭环**：`部署 → 用户异议/反例 → 撤回或再协商 → 重新规划`。伦理证书因此不是证明，而是**可废止的授权（defeasible authorization）**：它的价值不在于「永不被推翻」，而在于「能被及时、低成本地推翻」。可反驳性优于可证明性，这是开放式伦理世界的正确工程姿态。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（伦理可接受剖面）**
设情境 `c = (任务, 地点, 在场人群, 时间窗, 交互模式)`，利益相关者集合 `U = U_veto(c) ⊔ U_voice(c)`：`U_veto` 为直接受影响者（含其监护人或法定代表），`U_voice` 为更广泛的相关公众。用户 `u` 对动作 `a` 的可接受度：
```
ε_u : A × C → [0,1],   ε_u(a|c) 为可接受度（非概率）
```
`ε_u` 由共创造评分规（rubric）、学习价值模型与人工复核共同给出，**必须携带来源与置信区间**。

**定义 122（伦理包络）**
给定利益相关者阈值 `θ_u` 与公众阈值 `θ_voice`：
```
E_eth(c) = { a ∈ A | ∀u ∈ U_veto(c): ε_u(a|c) ≥ θ_u
                    ∧ median_{u∈U_voice(c)} ε_u(a|c) ≥ θ_voice }
```
否决权只给 `U_veto`；`U_voice` 用稳健聚合但**保留少数派异议日志**。`E_eth` 可以非凸、非连通，甚至为空——空包络意味着「当前情境下没有可部署动作」，这是合法且必须被系统承认的结果。

**定义 123（技术-伦理可部署域）**
```
A_deploy(c) = A_tech(c) ∩ E_eth(c),  A_tech(c) 由第 54 轮 α_S、ρ、δ_a 给出
```
第 54 轮的技能组合图 `G_S` 必须限制在 `A_deploy(c)` 上重建：伦理包络不是事后过滤器，而是**组合可行性的一等约束**。若某条动作兼容边落在 `E_eth` 外，则该边在伦理上不存在。

**定义 124（参与式共签证书 PCC）**
```
P = (J, E_eth, Scope, Epoch, Sig, CRL_root, Dissent, Contest)
```
- `J`：第 54 轮技术联合证书；
- `Scope = (用户集, 情境集, 动作子集, 时长)`：同意的**范围**；
- `Epoch`：审查纪元与下次复核时刻；
- `Sig`：利益相关者代表与审查方的**共签**（门限签名）；
- `CRL_root`：吊销日志根，执行前校验；
- `Dissent`：未被采纳的少数派异议（不可删除）；
- `Contest`：申诉/复核通道。
有效性谓词：
```
valid(P,c,t) ⇔ J.sound ∧ c∈Scope.contexts ∧ t<Epoch.expiry
              ∧ plan(A_T)⊆Scope.actions ∧ ¬revoked(CRL_root,Scope,t)
```

**定义 125（异议保持序与部署规则）**
伦理偏序：
```
a ≽_eth a'  ⇔  ∀u∈U: ε_u(a|c) ≥ ε_u(a'|c)
```
否决安全集 `P_eth(c) = { a∈A_tech(c) | ¬revoked(a) ∧ a 在 ≽_eth 下不被任何 a'∈E_eth(c) 严格支配 }`。
部署规则 `DPR`：
```
plan(A_T) ⊆ P_eth(c)           → 部署
plan(A_T) ⊆ A_tech \ E_eth     → 若仅违反 voice：升级人工审查并记录异议
                               若违反 veto：拒绝（不可被工程覆盖）
```

**定义 126（伦理审查闭环与审查状态）**
审查状态 `E-state ∈ {valid, contested, revoked, expired}`，闭环：
```
Review → Deploy → Contest → Revoke/Re-consent → Re-plan → Review'
```
关键时延 `τ_rev`：从用户撤回至边端停止相关动作的时间。**同意债**：
```
D(t) = ∫_0^t 𝟙[存在已部署动作 a ∉ valid_consent(τ)] dτ,   目标 D(t) ≡ 0
```

## 2. 关键算法 伪代码

### IP-121 EAP（Ethics-Aware Profile / 伦理包络构建）

```python
def build_ethics_envelope(A_tech, context, users, rubric, value_model):
    U_veto, U_voice = users.veto_set(context), users.voice_set(context)
    eps = {}
    for u in users.all():
        eps[u] = {a: value_model(u, a, context).combine(rubric[u]) for a in A_tech}
    # 否决集必须逐一显式通过，禁止用平均值掩盖
    veto_ok = {a for a in A_tech
               if all(eps[u][a].mean >= rubric[u].theta for u in U_veto)}
    voice_ok = {a for a in A_tech
                 if median(eps[u][a].mean for u in U_voice) >= rubric.theta_voice}
    E = veto_ok & voice_ok
    dissent = {a: {u: eps[u][a] for u in U_veto if a not in veto_ok} for a in A_tech}
    return EthicsEnvelope(E, eps, dissent, provenance=rubric.sources)
```

### IP-122 CO-CERT（参与式共签协议）

```python
def co_create_certificate(J, context, users, threshold_k):
    scope = negotiate_scope(users, context)          # 用户与家属共同商定范围
    E = build_ethics_envelope(J.A_tech, context, users, rubric, value_model)
    dissent = collect_dissent(users, context, E)     # 少数派异议不可删除
    sigs = [sign(u, hash(J, E, scope)) for u in users.representatives()]
    if len(sigs) < threshold_k:
        return ('reject', 'quorum_not_met', dissent)
    return ('ok', PCC(J=J, E_eth=E, Scope=scope,
                      Epoch=next_review(context), Sig=sigs,
                      CRL_root=crl.current_root(),
                      Dissent=dissent, Contest=open_channel(users)))
```

### IP-123 CRL-E（同意吊销账本）

```python
def execute_with_revocation_check(plan, cert, crl, freshness_proof, t):
    if not verify_freshness(crl.root, freshness_proof, t, tau_rev):
        return ('safe_stop', 'stale_revocation_state')   # 宁可停机，不带病执行
    for a in plan:
        if crl.revoked(cert.Scope, a, t):
            return ('replan', crl.reason(a))             # 触发再协商，不是静默替换
    return ('ok', plan)
```

### IP-124 DDR（异议保持部署规则）

```python
def dissensus_deploy_rule(plan, cert, context):
    if not cert_valid(cert, context):        return ('block', 'invalid_cert')
    for a in plan:
        if not veto_safe(a, cert.E_eth, context):
            return ('block', 'veto_violation', dissent_of(a))
        if a not in cert.E_eth.strict_set:
            return ('escalate', 'voice_dissent', dissent_of(a))
    return ('deploy', plan)
```

### IP-125 ECP（伦理耦合规划）

```python
def ethics_coupled_plan(task, G_S, A_deploy, cert):
    G = restrict_graph(G_S, A_deploy)         # 伦理包络外动作不参与组合
    path = a_star(G, task, cost=lambda e: e.cost + w_c*contest_risk(e))
```

### IP-126 CCE（共创反例引擎）

```python
def co_created_counterexamples(users, sim, task_family, rounds):
    scen = []
    for r in range(rounds):
        raw = elicit_scenarios(users, task_family)       # 自然语言/演示/现场走查
        S = parametrize(raw, sim)
        S = novelty_filter(S, sim.coverage_map)          # 去重与覆盖增益过滤
        w = importance_weight(S, users.participation)    # 修正参与不平等偏差
        scen += [(s, w) for s in S]
        sim.train_or_test(s)                             # 反例进入 GenSim 证据池
    return scen
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| EAP | O(\|A\|·\|U\|·\|C\|) | O(\|A\|·\|U\|) | 否决集完整、rubric 可追溯 |
| CO-CERT | O(\|U\|·\|A\| + k·sig) | O(\|U\|+\|A\|) | 门限签名、范围不可篡改 |
| CRL-E | O(log n) 查询 | O(n) 日志 | append-only、新鲜度可验证 |
| DDR | O(\|A_T\|·\|U\|)（可预计算） | O(\|A\|·\|U\|) | 否决安全、异议不丢失 |
| ECP | O(\|V\|log\|V\|+\|E\|·\|A_deploy\|) | O(\|V\|+\|E\|) | 包络内路径最优 |
| CCE | O(rounds·(\|U\|+\|S\|·sim)) | O(\|S\|) | 重要性加权、无重复计数 |

**命题（不存在标量伦理分数）**
设 `|U_veto|≥3` 且偏好不受限。若 `f:[0,1]^n→[0,1]` 满足一致性（全体认为 a 不劣于 a' 则 f(a)≥f(a')）、无关备选独立性、非独裁，则不存在这样的 `f`（Arrow）。故任何单一 `θ_eth` 要么独裁、要么可被阈值套利。**推论**：伦理证书必须保留向量/偏序与异议，不能用 `min_u ε_u` 或加权和冒充「客观伦理」。

**正确性定理（可废止授权的条件 soundness）**
设 (A29) `U_veto(c)` 枚举完整且 `Scope` 覆盖全部直接受影响者；(A30) 共签门限 `k` 保证单一运营方无法伪造范围；(A31) 吊销传播时延 `τ_rev ≤ τ_max` 且 CRL-E 不可回滚；(A32) 情境检测 `ĉ(t)` 对关键情境集 `C_crit` 为保守过近似。则在一个部署周期内：
```
P(伦理违规事件) ≤ P(情境漏检) + P(范围伪造) + P(吊销过期)
                  + P(|ε̂ - ε| > margin) + P(未预见的开放世界情境)
```
前四项是**可工程化压缩的治理残差**；最后一项不可消除，故证书只能是**可废止授权**，其安全性由 `τ_rev` 与申诉通道而非「绝对证明」保证。

**推论（共创覆盖的双面性）**
若共创场景与真实长尾同分布，则加入 `S` 会弱提升覆盖估计；但参与者在时间、表达能力、利益强度上不均衡，直接汇总会引入**共创偏差**。必须以重要性权重 `w` 修正，并对未参与群体做保守包络（宁可高估其否决风险），否则「共创」会把**发声者偏好**伪装成**全体偏好**。

## 4. 实验设计 E162–E167

| 实验 | 指标 | 目标 |
|---|---|---|
| E162 伦理包络一致性 | 与独立伦理小组的 Cohen's κ / MAE | κ ≥ 0.70，MAE ≤ 0.10 |
| E163 共创覆盖增益 | 用户场景带来的新增关键失效模式 | 新增 ≥ 20%（相对仅工程师） |
| E164 吊销时延与同意债 | `τ_rev` 分布、`D(t)`、过期同意事故 | P95 ≤ 1s，`D≡0` |
| E165 异议与否决行为 | 误否决率、僵局率、升级率 | 误否决 ≤ 10%，僵局可解释 |
| E166 合法性与信任 | 感知控制感、理解度、接受意愿（混合方法） | 显著提升且效应量可报告 |
| E167 伦理洗白红队 | 运营方尝试「收买/绕过」共创的检出率 | 审计检出率 ≥ 90% |

E162 需双盲：价值模型开发者不见伦理小组结论；E163 需预注册覆盖增益指标；E166 需 IRB 批准与知情同意（本轮主题的自我应用）；E167 用对抗性运营脚本测试 CRL-E 与门限签名是否真的不可绕过。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 伦理洗白：共创沦为盖章 | 高 | 独立否决席位 + 少数派异议日志 + 外部审计 |
| 价值模型编码偏见 | 高 | 参与式 rubric + 分层校准 + 未参与群体保守包络 |
| 否决权导致治理僵局 | 高 | 明确否决范围 + 时限升级 + 退出/降级预案 |
| 撤回引发重规划震荡 | 中 | 吊销批量与 hysteresis + 安全停机优先 |
| 偏好数据隐私 | 高 | 本地差分隐私 + 不落原文 + 最小必要收集 |
| 与法规/IRB 口径冲突 | 中 | 法规映射表 + 审查方共签 + 可审计留痕 |
| 包络非凸导致组合不可行 | 中 | ECP 分层剪枝 + 多包络切片 + 人工复核 |
| 参与不平等/负担 | 中 | 补偿、无障碍参与、代理代表机制 |

## 6. 本轮最大风险

**一句话**：本轮把伦理审查从事后合规提升为证书的治理层、把用户从数据源提升为共同作者，但**最大风险是「伦理洗白」——共创可能只是借来用户的合法性，而 ε 的定义权、否决权与撤回权仍握在运营方手里；更根本的是，Arrow 式异质性意味着任何单一伦理分数都不 sound**，因此系统必须把异议、否决与撤回显式暴露在证书里，而不是用一个 `θ_eth` 把分歧平均掉；否则整套技术证书越 sound，越会成为合法性漂白的机器。

# 第 55 轮产物 · 创新点清单 v32：GroundEdge-GovSim（EAP×CO-CERT×CRL-E×DDR×ECP×CCE）

> 承接第 54 轮产物 v31。上一版把技能组合推进到「动作剖面 + 鲁棒性谱 + 云边映射」的联合证书 `J`，但仍默认**部署授权是免费且永久的**。本轮增加 **伦理-治理层**，把「能不能做」升级为「在谁的授权下、对谁、做多久、可否反悔」：
> - **EAP（Ethics-Aware Profile）**：利益相关者索引的伦理可接受剖面与伦理包络 `E_eth`；
> - **CO-CERT（Participatory Co-signing）**：用户共同定义范围并共签证书；
> - **CRL-E（Consent Revocation Ledger）**：同意可撤回、可过期、可审计；
> - **DDR（Dissensus-Preserving Deployment Rule）**：保留异议与否决的部署规则；
> - **ECP（Ethics-Coupled Planning）**：在 `A_tech ∩ E_eth` 上做组合规划；
> - **CCE（Co-created Counterexample Engine）**：用户反例反哺 GenSim 证据池。
>
> IP 编号：IP-121~IP-126（共 6 个新增），并升级 IP-115/117/118/120 以纳入治理约束。命名：**GroundEdge-GovSim**（Governance × Simulation）。

## 0. 核心 IP 设计

| 编号 | 名称 | 类型 | 关键改进 |
|---|---|---|---|
| IP-121 | EAP Ethics-Aware Profile | 新增 | 伦理剖面 `ε_u(a\|c)`，伦理包络 `E_eth(c)`，否决集显式建模 |
| IP-122 | CO-CERT Participatory Co-signing | 新增 | 范围 `Scope` + 纪元 `Epoch` + 门限共签 + 异议日志 |
| IP-123 | CRL-E Consent Revocation Ledger | 新增 | append-only 吊销日志、执行前校验、新鲜度证明 |

## 2. 关键算法 伪代码

### IP-121 EAP

```python
def build_ethics_envelope(A_tech, context, users, rubric, value_model):
    U_veto, U_voice = users.veto_set(context), users.voice_set(context)
    eps = {u: {a: value_model(u, a, context).combine(rubric[u], weight=True)
               for a in A_tech} for u in users.all()}
    veto_ok  = {a for a in A_tech
                if all(eps[u][a].mean >= rubric[u].theta for u in U_veto)}
    voice_ok = {a for a in A_tech
                if median(eps[u][a].mean for u in U_voice) >= rubric.theta_voice}
    E = veto_ok & voice_ok
    dissent = {a: {u: eps[u][a] for u in U_veto if a not in veto_ok}
               for a in A_tech}
    assert all(e.source for row in eps.values() for e in row.values())
    return EthicsEnvelope(E, eps, dissent,
                          provenance=rubric.sources,
                          confidence=min_confidence(eps))
```

### IP-122 CO-CERT

```python
def co_create_certificate(J, context, users, threshold_k):
    scope = negotiate_scope(users, context)     # 用户/监护人共同商定动作与情境
    E = build_ethics_envelope(J.A_tech, context, users, rubric, value_model)
    dissent = collect_dissent(users, context, E)  # 不可删除，随证书发布
    payload = hash(J, E, scope, next_review(context))
    sigs = [sign(u, payload) for u in users.representatives()]
    if len(sigs) < threshold_k:
        return ('reject', 'quorum_not_met', dissent)
    return ('ok', PCC(J, E, scope, Epoch=next_review(context),
                      Sig=sigs, CRL_root=crl.current_root(),
                      Dissent=dissent, Contest=open_channel(users)))
```

### IP-123 CRL-E

```python
def revoke(user, action_set, context_set, reason):
    entry = (user, action_set, context_set, now(), reason)
    crl.append(entry)                # append-only，禁止重写历史
    return crl.root()

def execute_with_revocation_check(plan, cert, crl, freshness_proof, t, tau_rev):
    if not verify_freshness(crl.root, freshness_proof, t, tau_rev):
        return ('safe_stop', 'stale_revocation_state')  # 宁可停机
    for a in plan:
        if crl.revoked(cert.Scope, a, t):
            return ('replan', crl.reason(a))            # 触发再协商
    return ('ok', plan)
```

### IP-124 DDR

```python
def dissensus_deploy_rule(plan, cert, context):
    if not cert_valid(cert, context):
        return ('block', 'invalid_cert')
    for a in plan:
        if not veto_safe(a, cert.E_eth, context):
            return ('block', 'veto_violation', cert.Dissent.get(a))
        if a not in cert.E_eth.strict_set:
            return ('escalate', 'voice_dissent', cert.Dissent.get(a))
    return ('deploy', plan)
```

### IP-125 ECP

```python
def ethics_coupled_plan(task, G_S, cert, context):
    A_deploy = cert.J.A_tech & cert.E_eth(context)    # 伦理包络外动作不存在
    G = restrict_graph(G_S, A_deploy)
    path = a_star(G, task,
                  cost=lambda e: e.cost + w_c * contest_risk(e, cert))
    if path is None:
        return ('no_ethical_plan', 'empty_envelope', explain_envelope(cert))
    return ('ok', certify(path, cert, context))
```

### IP-126 CCE

```python
def co_created_counterexamples(users, sim, task_family, rounds):
    scen = []
    for _ in range(rounds):
        raw = elicit_scenarios(users, task_family)      # 语言/演示/走查
        S = [parametrize(r, sim) for r in raw]
        S = novelty_filter(S, sim.coverage_map)
        w = importance_weight(S, users.participation)   # 修正参与偏差
        for s in S:
            sim.add_evidence(s, weight=w[s], source='co-creation')
        scen += [(s, w[s]) for s in S]
    return scen
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| EAP | O(\|A\|·\|U\|·\|C\|) | O(\|A\|·\|U\|) | 否决集完整，rubric 来源可追溯 |
| CO-CERT | O(\|U\|·\|A\| + k·sig) | O(\|U\|+\|A\|) | 门限签名，范围防篡改 |
| CRL-E | O(log n) 查询 / O(1) 追加 | O(n) 日志 | append-only，新鲜度可验证 |
| DDR | O(\|A_T\|·\|U\|) | O(\|A\|·\|U\|) | 否决安全，异议不丢失 |
| ECP | O(\|V\|log\|V\|+\|E\|·\|A_deploy\|) | O(\|V\|+\|E\|) | 包络内路径最优 |
| CCE | O(rounds·(\|U\|+\|S\|·sim)) | O(\|S\|) | 重要性加权，无重复计数 |

**命题 1（标量伦理分数不存在）**
在 `|U_veto|≥3`、偏好不受限时，不存在同时满足一致性、无关备选独立性与非独裁的聚合 `f:[0,1]^n→[0,1]`（Arrow）。故单一 `θ_eth` 必然独裁或可套利；`min_u ε_u` 与加权和都不是 sound 的伦理证书，只能作为**辅助排序**。

**命题 2（共创覆盖的双面性）**
记共创场景分布 `Q`、真实长尾 `P`。若 `Q=P`，加入 CCE 场景弱提升覆盖估计；若 `Q≠P`（只有高表达能力群体参与），则未加权汇总使覆盖估计产生偏差 `‖Q−P‖_TV` 量级。以重要性权重 `w=dP/dQ` 可纠偏，且对未参与群体必须采用**保守包络**（高估其否决风险），否则共创会成为**发声者偏好冒充全体偏好**的通道。

**正确性定理（可废止授权的条件 soundness）**
在第 54 轮 (A22)–(A28) 之外，假设：
**(A29)** `U_veto(c)` 枚举完整、`Scope` 覆盖全部直接受影响者；
**(A30)** 共签门限 `k` 使单一运营方无法伪造范围（`≤k−1` 个签名不可用）；
**(A31)** `τ_rev ≤ τ_max`，CRL-E append-only 且拒绝回滚；
**(A32)** 情境检测 `ĉ(t)` 对关键情境集 `C_crit` 保守过近似。
则单个部署周期的伦理违规概率满足：
```
P(EV) ≤ P(情境漏检) + P(范围伪造) + P(吊销过期)
        + P(|ε̂−ε|>margin) + P(开放世界未预见)
```
四项治理残差可被 EAP/CO-CERT/CRL-E 逐项压缩；末项不可消除，因此 PCC 的正确性定义不是「永真」，而是**可废止（defeasible）**：任何授权都能在 `τ_rev` 内被撤回，且撤回路径本身可审计。

| E166 合法性 | 共创前/后（混合方法） | 控制感、理解度、接受意愿 | 显著提升并报告效应量 |
| E167 洗白红队 | 对抗性运营方（收买/绕过共创） | 审计检出率、绕过成功数 | 检出≥90%，绕过=0 |

补充分析：
- **消融**：去掉 `U_veto` 仅用 `median` → 预期少数派被系统性牺牲；去掉 CRL-E → 预期出现「过期同意」事故。
- **代价**：`E_eth` 交集使可部署动作域收缩，报告 `vol(A_deploy)/vol(A_tech)` 与任务成功率损失，验证伦理约束不是零成本。
- **纵向**：审查纪元间 `E-state` 迁移，统计 `valid→contested→revoked→valid` 的驻留时间。

## 6. 本轮最大风险

**一句话**：本轮把伦理审查从事后合规提升为证书的治理层、把用户从数据源提升为共同作者，但**最大风险是「伦理洗白」——共创可能只是借来用户的合法性，而 ε 的定义权、否决权与撤回权仍握在运营方手里；更根本的是，Arrow 式异质性意味着任何单一伦理分数都不 sound**，因此系统必须把异议、否决与撤回显式暴露在证书里，而不是用一个 `θ_eth` 把分歧平均掉；否则整套技术证书越 sound，越会成为合法性漂白的机器。
