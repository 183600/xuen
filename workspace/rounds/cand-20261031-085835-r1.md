# 灵感循环第 1 轮（状态文件第 13 轮）· REV-GUARD：把 94 个官方得分点编译成可逆状态机，让 VLA 知道自己走到哪、什么时候该回头

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是灵感循环第 1 轮，状态文件承接第 12 轮 CHUNK-SERVO（按第 13 轮记录），三个灵感词是「场景理解」「状态机」「情感语音」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是把它们从「观测层」「执行层」推进到「阶段层」：**VLA 仍然负责产生动作，但由一张从官方 94 个得分点编译出来的可逆阶段图，决定现在该信谁、该往前走、该回头、该重试，还是该跳过。**

## 0. 先给结论：榜首仍不到 30%，真正的共享瓶颈是「阶段失明」

截至 2026-10-31，官网榜单仍是同一批 8 个模型：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。头尾只差 9.2pp。榜单仍是预览/合成数据：`leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`，8 模型 ×32 任务的 `step ~ success` 回归 R² > 0.999999，成功率出现 27.29%、27.85% 这类非 10% 整数倍，详情页 32 个任务视频仍是占位。**所以本轮不把榜单当 SOTA，也不从榜单任务排名里挖创新点。**

真正有价值的新事实来自官方任务信息 JSON：32 个任务一共 **94 个官方得分点**，每个任务满分 100，步骤分是 30/30/40、25/25/25/25、50/50、20×5 这类**结构化权重**；同时，官方在「人为干扰」泛化里写得很具体，而且大量干扰是**撤销/回退**：

- T19 拉上拉链：**「拉上拉链之后拉开」**；
- T16 叠毛巾：**「将叠完的毛巾翻开」**（两条备注都是）；
- T14 倒出药品：**「拧开盖子之后拧动回来」**；
- T17 整理文具：**「笔盒合上之后手动打开」**；
- T27 碗具堆叠：**「叠了第二个之后拿下第二个」**；
- T12 开锁：**「中途把锁拿走」**；
- T10 插插头：**「将插头拔起」**；
- T24 传送带分拣：**「可乐快到了然后放回传送带起点」**。

这组备注暴露了一个结构性弱点：**以 action chunk 为主的 VLA 普遍没有显式的「官方步骤状态」**。它不知道自己是「已经拉上拉链」还是「还没拉上」，更不知道「刚才拉上的拉链又被人拉开了」。它只会按当前图像继续输出一个动作 chunk；当世界被人类回退时，它会把「继续拉」执行成「把拉链头推坏」。

所以本轮的押注是 **REV-GUARD**：

> 把官方 94 个得分点编译成一张**可逆阶段图**；在同一个 WLA checkpoint 上加一个**阶段头**预测「现在在哪、进度多少、置信多少」；用**任务引导的谓词**做可验证证据；用**确定性 Guard 自动机**做前向、回退、卡住、重试、跳过；用**anytime 子目标调度**在 180s 内先锁步骤分、再冲成功率；用**风险/紧迫度/人类撤销意图**替代无法落地的「情感语音」。

一句话：**把「预测 1 秒动作」升级为「维护一张 94 个得分点的可逆状态图」，让 VLA 从开环执行器变成有阶段记忆、会回头、会止损的阶段执行器。**

## 1. 本轮核实的事实（只列会改变方案的）

### 1.1 榜单仍是预览，不能当实验分布

- 8 个模型、32 个任务、平均时长约 44s；榜单 JSON 的 `generated_from = "gen_leaderboard.py"`。
- 对每个模型做 `step_score ~ success_rate` 回归，R² > 0.999999，最大残差 <0.006；形式是 `step ≈ k_model × success`，不是实测步骤分。
- 详情页 `details.html?model=MolmoAct2&user=DexHacker` 的 32 个任务视频全部是「测试视频占位，后续可替换为真实视频文件」。
- 8 个模型的 32 维任务成功率两两相关，平均 off-diagonal 相关系数约 0.098；真实任务难度应当让不同模型正相关。
- 每任务只有 10 次 trial，成功率却不是 10% 的整数倍。

**用法**：只把 29.7% 当「赛事方预览上限/难度信号」；真实步骤分和失败分布必须用单任务不计分通道测。

### 1.2 官方 94 个得分点：这是赛题方免费给的 reward machine

32 个 `tasks_v2/<slug>/info.json` 的 `score_steps` 是结构化的，不是一段自然语言。几个例子：

| 任务 | 官方步骤（分数） | 人为干扰备注 | 对状态机的含义 |
|---|---|---|---|
| T01 挂杯子 | 抓住杯把（50）→ 挂到杯架标记位置（50） | 杯子向后/向右 | 先抓后挂，前置依赖强 |
| T14 倒出药品 | 打开药瓶盖（50）→ 倒出药品（50） | **拧开盖子之后拧动回来** | 完成态可被回退，必须能回到「开盖」 |
| T16 叠毛巾 | 挥正（20）→ 上下对折（20）→ 左折（20）→ 右折（20）→ 放到旁边（20） | **将叠完的毛巾翻开** | 折叠可被翻开，回退可能跨多步 |
| T17 整理文具 | 摆正文具盒（20）→ 放文具1/2/3（各20）→ 盖上（20） | **笔盒合上之后手动打开** | 盖盒是「可撤销的完成」 |
| T19 拉上拉链 | 摆正收纳包（50）→ 拉上拉链（50） | **拉上拉链之后拉开** | 最典型的「完成→回退」 |
| T27 碗具堆叠 | 碗1放中间（30）→ 碗2叠上（30）→ 碗3叠上（40） | **叠了第二个之后拿下第二个** | 回退会破坏后续堆叠的前提 |
| T10 插插头 | 抓插排（30）→ 抓插头（30）→ 插入（40） | **将插头拔起** | 插入态可被拔回 |
| T12 开锁 | 抓锁（30）→ 拧钥匙（30）→ 拨铁环（40） | **中途把锁拿走** | 目标物可能整体消失，必须重定位/放弃 |
| T24 传送带分拣 | 抓食品（50）→ 放到对应架子（50） | **快到了然后放回起点** | 动态目标被回退到起点 |
| T26 插网线 | 抓网线（30）→ 抓网口（30）→ 插入（40） | **把网线移开/把插口移开** | 目标物/受器都可能移动 |

这 94 个点有三个价值：

1. **它们是官方评分函数**，不是我们的猜测。步骤分是排名的 tie-breaker，先锁步骤分有真实收益。
2. **它们给出阶段顺序和权重**，可以直接编译成状态图，不需要 LLM 在线规划。
3. **它们给出人为干扰的「回退类型」**，可以提前设计反向边和恢复原语。

### 1.3 API 修正：chunk 是固定的；腕部有内参；没有音频

- `action_chunk_size` 是**提交级固定值**，握手时确定；chunk 内没有新观测，也没有打断机制。第 12 轮设想的「按阶段改 chunk 长度」不成立。正确做法是：全局选一个 `T_a`（建议 5），VLA 内部仍可规划 30 步，执行时按固定 5 步切片；阶段只调制**速度因子/伺服增益**，不改 chunk 长度。
- 腕部相机并非没有内参。HangCup 的 `meta/info.json` 里 `wrist_left.color.camera_matrix = [[436.4058,0,323.9217],[0,435.9215,242.9332],[0,0,1]]`，`wrist_right = [[435.1151,0,319.0249],[0,434.4995,240.9933],[0,0,1]]`，`distortion.inverse_brown_conrady`，640×480。第 12 轮「腕部无内参」的结论要纠正；腕部 2D 伺服不必先做棋盘格标定，但仍需验证真实机器人与数据集标定是否一致。
- 头部双目已标定：基线约 **58.2526 mm**，`fx≈282.37`，`rectified=true`；`state_d435` 是头相机在 base 系的 6D 位姿，可由 `lower_body[-3:]` 在线恢复外参。
- 四路视频的 `has_audio` 都是 **false**；API 没有音频；规则里的「人为干扰」是物理干扰（临时改变物品位置等），不是语音。**「情感语音」在本赛题没有接口，必须剪枝。**

### 1.4 数据与官方基座：不要从零训

- 32 个 HF 数据集合计 **33,276 episodes / 18,282,246 frames / 169.28 h / 30fps**；单任务 969–1,533 episodes；平均时长 6.2s（HangCup）–37.6s（ToolboxStorage）。
- 官方 **UnifoLM-WLA-1.0**：6B 参数，约 2,500h 真机数据，64 个任务；默认 `chunk_size=30`、`target_fps=30`、4 步扩散去噪；微调时冻结 VLM，只训 DiT action head + robot-state projector，单张 **24GB** GPU 可跑；统一动作 54 维、状态 60 维。
- 官方仿真：`unitree_sim_isaaclab`、`unitree_mujoco`、`unitree_rl_mjlab`、`unitree_rl_lab`，足够搭轻量数字孪生做扰动/回退注入。
- 战略结论不变：用 WLA Base 做 action-head 微调，把算力投到**阶段层、执行层、单任务评测**；但 WLA 是否已覆盖挑战赛 32 任务、`pivot` 语义是否完全一致，必须先在单任务通道实测。

### 1.5 为什么「情感语音」是陷阱，而不是创新点

我一开始想把「情感语音」做成语音情绪识别：听出人类的不耐烦/紧急，调整机器人速度。但三条事实把这条路堵死：

1. 数据四路视频都没有音轨；
2. API 观测没有音频；
3. 规则的人为干扰是物理动作，不是说话。

所以本轮**明确剪枝**：不做语音识别、不做情感 TTS、不做第二个音频模型。剪枝不是浪费，它逼出了更硬的问题：赛题里的「情感」其实是**人类干扰带来的风险、紧迫、不信任**。这可以转成一个内部风险向量，调制状态机，而不需要麦克风。

### 1.6 本轮新增的判断/实验（一句话版）

- **新事实**：官方 94 个结构化得分点；人为干扰备注大量是撤销/回退；腕部有 color 内参；`action_chunk_size` 固定；数据/API 无音频。
- **新判断**：共享瓶颈从「最后 3 厘米」升级为「阶段失明」；线性 FSM 不够，需要可逆阶段图；「情感语音」应剪枝，转成内部风险/紧迫/信任向量。
- **新实验**：StageHead 阶段 F1/ECE；undo 注入恢复率/误触发；anytime 调度的步骤分；5 个代表任务的单任务 A/B。

## 2. 三个灵感词怎么落到方案里

| 灵感词 | 字面做法（剪枝） | 本轮采用 | 不做什么 |
|---|---|---|---|
| **场景理解** | 建完整 4D 场景图/第二个分割模型 | **验证优先的任务引导谓词**：每个任务只理解 2–5 个官方得分点需要的谓词 | 不做全场景图；不加载第二个学习模型；不做 6D 物体位姿网络 |
| **状态机** | 线性 FSM，进度只增不减 | **可逆阶段图 + Guard 自动机**：前向、回退、卡住、重试、跳过 | 不假设单调进度；不做 32 个任务各一个策略 |
| **情感语音** | 语音情绪识别/情感 TTS | **内部风险/紧迫/挫败/信任向量**，调制速度、重试、跳过 | 不做音频接口；不做第二个音频模型；不做「情绪标签」监督 |

### 2.1 场景理解：不是「看懂整个场景」，而是「验证当前得分点」

官方评分只关心 94 个步骤谓词，例如「杯把被抓住」「拉链拉上」「碗2叠在碗1上」「网线插入网口」。我们不需要知道桌上每个物体的 6D 位姿，只需要知道**当前阶段的前置/完成谓词是否成立**。这叫 **verification-first scene understanding**：

- 任务引导：只检测与当前任务/阶段相关的 2–5 个物体/关系；
- 相对几何：用「受器→夹爪」相对位姿，不用绝对世界坐标；
- 证据融合：阶段头给先验，谓词给证据，置信度低就回退 VLA；
- 确定性：谓词用经典 CV/几何，不引入第二个学习模型。

### 2.2 状态机：不是「进度条」，而是「可逆图」

线性 FSM 的隐含假设是「世界只会向前」。但官方人为干扰明确会撤销：拉链拉开、毛巾翻开、盖子拧回、碗拿走。所以状态机必须是**图**，不是链：

- 前向边：完成一个得分点；
- 反向边：检测到完成态被破坏，退回上一个稳定态；
- 重试边：同一阶段内滑移/没抓住；
- 跳过边：独立子目标卡住且时间不够，先锁其他分；
- 恢复边：目标物消失/人拿走，重新定位或放弃。

### 2.3 情感语音：从「听情绪」转成「算风险」

内部风险向量 `z_t = [confidence, risk, urgency, frustration, trust]`：

| 维度 | 技术变量 | 作用 |
|---|---|---|
| 置信 | 阶段头 `c_t` + 谓词置信 | 决定信 VLA 还是信 Guard |
| 风险 | 谓词不确定 + 人类编辑残差 | 决定减速/停/恢复 |
| 紧迫 | 剩余时间 / 预估完成时间 | 决定是否跳过独立子目标 |
| 挫败 | 同一子目标连续失败次数 | 决定换恢复原语/换策略 |
| 信任 | VLA 与 Guard 的一致率 | 决定控制权分配 |

这不是「情绪识别」，是**风险敏感控制**。它让「情感语音」这个词在无音频赛题里仍然有技术落点。

## 3. 诊断：阶段失明（stage blindness）

把一次失败拆成三层：

```text
语义层：VLA 知道「要挂杯子」
阶段层：VLA 不知道「已经抓住杯把，下一步是挂」
执行层：VLA 不知道「杯把在腕部图像里偏左 3px，应该往右 0.4mm」
```

第 10 轮 FACT-VLA 解决语义/阶段标签，第 11 轮 GEO-RESIDUAL 解决「世界变了」，第 12 轮 CHUNK-SERVO 解决「最后 3 厘米」。但三者都默认「阶段是单调的」。本轮补的是**阶段层的可逆性**。

形式化：

- 任务 `τ` 有官方步骤 `s_1…s_n`，权重 `w_i`，`Σw_i=100`；
- 谓词 `φ_i(o_t) ∈ {0,1}` 表示第 `i` 步是否完成；
- 进度 `p_t = Σ_i w_i·1[φ_i(o_t)=1] / 100`；
- 成功 `Y = 1[所有必要 φ_i=1]`。

线性 FSM 假设 `p_t` 单调不减；真实世界有：

1. **人类撤销**：`φ_i` 从 1 变 0；
2. **机器人滑移**：抓取后物体掉落，`φ_grasp` 变 0；
3. **目标移动**：受器/目标整体移动，`φ` 的相对几何失效；
4. **时间不够**：某个子目标反复失败，继续投入会拖垮其他分。

这四种情况对应四种动作：`BACKTRACK`、`RETRY`、`RELOCALIZE`、`SKIP`。没有阶段图的 VLA 只会继续执行当前 chunk，把「已完成」当成「未完成」，或者把「已撤销」当成「已完成」。

### 3.1 为什么现有工作没有完全解决

| 工作 | 做了什么 | 没做什么（本轮的差异） |
|---|---|---|
| **VLA-Corrector**（arXiv 2609.06508） | 学习型 verifier 估计进度/风险；语义阶段（approach/align/grasp/transport/place）；用 stage-conditioned prompt 让冻结 VLA 恢复 | 没有官方 94 步评分图；没有反向边/人类撤销；verifier 是外部学习模型；没有 180s anytime 调度 |
| **Recova**（arXiv 2610.01178） | 数字孪生里诊断失败、测试恢复程序；单独的任务策略 + 恢复策略；真机 DAgger | 需要单独恢复策略/数字孪生；不是单 checkpoint；不针对官方步骤分 |
| **RoboRecover**（arXiv 2609.28952） | 从执行偏差状态重建场景，评测恢复能力 | 是 benchmark，不是在线方法；不解决官方 94 步图 |
| **FailSafe**（arXiv 2510.01642） | 自动生成失败-恢复数据，微调 VLM 做失败推理 | 第二个 VLM；没有官方评分图；主要在 ManiSkill |
| **ChronoGraph**（arXiv 2609.39665） | 功能 4D 场景图 + VLM 做交互理解/规划 | 重；需要训练 VLM；不是阶段 FSM；不解决固定 chunk/180s |
| **Positional Blind Spots**（arXiv 2608.01573） | 发现并定位 VLA 的空间盲区，用 LoRA 微调缓解 | 离线微调；不是在线回退/恢复 |

**本轮的 delta 不是「阶段感知恢复」这个大类**——VLA-Corrector 已经做了。我们的 delta 是四个组合：

1. **官方 94 步评分图**直接编译，不是人工定义语义阶段；
2. **同一个 checkpoint 内的阶段头**，不是外部 verifier/第二个模型；
3. **反向边 + 人类撤销检测 + anytime 子目标调度**，不是只做前向恢复；
4. **固定 API chunk 内的阶段条件化执行**，不是改 chunk 长度或加第二个策略。

## 4. REV-GUARD 方法

### 4.1 总架构

```text
官方 tasks_v2/<slug>/info.json（32 任务 / 94 步 / 权重 / 人为干扰备注）
        │
        ▼
StageGraph Compiler（离线，确定性）
  ├─ 步骤→谓词 DSL
  ├─ 前向边/反向边/重试边/跳过边
  ├─ 权重 w_i、恢复原语 ρ_i
  └─ 任务图 G_τ
        │
        ▼
Per-port GuardRuntime（CPU，确定性）
  ├─ StageHead（同一 WLA checkpoint）→ q_t, progress, confidence
  ├─ SceneProbe（任务引导谓词）→ φ_i, uncertainty
  ├─ Guard 自动机 → FORWARD / HOLD / BACKTRACK / RETRY / SKIP / RECOVER
  ├─ Anytime Scheduler → 下一个子目标
  └─ Stage-conditioned Servo → σ(s), K(s)
        │
        ▼
Shared WLA server（GPU）：30 步规划，固定 5 步执行
```

- 唯一学习模型：WLA（含 StageHead，同一 checkpoint）。
- 确定性控制器：StageGraph、Guard、Scheduler、Servo；无学习权重。
- 数据资产：33k 成功演示 → 阶段标签/目标库；不是第二个模型。
- 数字孪生：只做回退注入/标定/压力测试，不训练大策略。

### 4.2 StageGraph：把官方步骤编译成可逆图

图定义：

```text
G_τ = (V, E_f, E_b, E_r, E_s, w, φ, ρ)
V   : 稳定阶段（通常 n+1 个）
E_f : 前向边（完成第 i 步）
E_b : 反向边（第 i 步完成态被破坏）
E_r : 重试边（同一阶段内滑移/没抓住）
E_s : 跳过边（独立子目标，时间不够）
w   : 官方权重
φ   : 完成谓词
ρ   : 恢复原语（重抓/重对齐/重插/重拉/重定位）
```

T19 的例子：

```text
v0 --φ_upright--> v1 --φ_zipped--> v2
v2 --¬φ_zipped / human_undo--> v1
v1 --¬φ_upright--> v0
v1 --slip--> v1 (RETRY)
```

T27 的例子：

```text
v0 --φ_bowl1_in--> v1 --φ_bowl2_on--> v2 --φ_bowl3_on--> v3
v2 --¬φ_bowl2_on / human_removed--> v1
v3 --¬φ_bowl3_on--> v2
```

编译器规则：

1. 从 `score_steps` 抽动词/对象/受器；
2. 动词映射到谓词模板：`抓/夹→grasped`、`放/放入→in`、`挂→hanging`、`叠→on/stacked`、`插→inserted`、`拔→removed`、`拉/拉上→zipped`、`打开→open`、`盖上→closed`、`拧→rotated`、`摆正→upright`；
3. 重复物体（水果1/2/3、碗1/2/3）不强制全序，用对象级谓词 + 偏序；
4. 有前置依赖的步骤（开盖→倒、抓→挂、叠碗1→叠碗2）加强制前向边；
5. 从 `human_*_note` 抽回退类型，补反向边和恢复原语；
6. 权重直接取官方分数；步骤分是 tie-breaker，所以调度器必须知道权重。

这一步的产出是 32 张图、94 个步骤谓词、约 150–250 条边。**不需要在线 LLM 规划**；LLM 只在离线帮助解析动词，运行时是确定性图。

### 4.3 StageHead：同一个 checkpoint 内的阶段先验

- 输入：WLA 的 VLM/DiT 特征 + 本体状态；
- 输出：8 类宏阶段 `q_t`（approach / align / grasp / transport / insert-or-place / manipulate / verify / recover）、进度 `r_t∈[0,1]`、置信 `c_t`；
- 结构：2 层 MLP + 可选 cross-attention；参数量 <5M；
- 训练：动作损失 + 阶段 CE + 进度 MSE + 置信校准（ECE）；
- 标签：从成功演示自动分割 + 160 帧人工校正（32 任务 ×5 帧）；
- 资源：冻结 VLM，只训 DiT action head + StageHead；24GB 可跑；
- 合规：StageHead 与 WLA 在同一个 checkpoint 文件/同一次前向里，不是第二个模型；
- 回退：若联合训练不稳定，先用冻结 VLM 特征的线性 probe；仍是同一 checkpoint 的附加头。

StageHead 的作用不是替代谓词，而是给谓词提供**阶段先验**：当谓词不确定时，阶段头告诉 Guard「现在大概率在拉链阶段」，避免把「包被移动」误判成「已经拉好」。

### 4.4 SceneProbe：任务引导的 2–5 个谓词

谓词 DSL：

```text
grasped(x)          # 夹爪闭合 + 物体随夹爪运动
in(x, y)            # 物体 x 在受器 y 内/上
on(x, y)            # x 叠在 y 上
inserted(x, y)      # x 插入 y（网线/插头/试管）
zipped(x)           # 拉链闭合（拉链头位置 + 齿合线）
open(x) / closed(x) # 盖子/盒子
upright(x)          # 摆正
stacked(x, y)       # 堆叠稳定
removed(x)          # 从原位移除
```

每个任务只启用 2–5 个谓词，总共 94 个。实现：

- 头部双目：局部 ROI 深度/视差 + 颜色/边缘；
- 腕部：夹爪-物体相对运动、拉链/网口局部特征；
- 本体：EE 位姿、夹爪开合、关节电流（仅作辅助，API 没有力）；
- VLM 特征：同 checkpoint 的 encoder 做开放词汇匹配（不加载第二个模型）；
- 输出：`φ_i∈{0,1}` + `uncertainty`；
- 校准：用数据集内参 + `state_d435` 恢复外参；真实机器人首次运行做一次重投影检查；置信低就回退 VLA。

### 4.5 Guard 自动机：前向、回退、重试、跳过、恢复

状态：

```text
FORWARD   正常执行当前阶段
VERIFY    到达阶段边界，等谓词确认
HOLD      人靠近/证据冲突，暂停
BACKTRACK 完成态被破坏，退回上一个稳定态
RETRY     同一阶段滑移/没抓住，重试
RECOVER   目标物消失/受器移动，重定位或放弃
SKIP      独立子目标卡住且时间不够
DONE      成功/时间到
```

转移规则（核心）：

| 触发 | 条件 | 动作 |
|---|---|---|
| 阶段完成 | `φ_i=1` 且 `c_t` 高 | `FORWARD`，更新进度 |
| 人类撤销 | `φ_i` 1→0，`edit_t` 高，夹爪未持有物体 | `BACKTRACK` 到 `v_{i-1}`，重做第 i 步 |
| 机器人滑移 | `φ_grasp` 1→0，夹爪持有物体，`motion_residual` 高 | `RETRY` 重抓/重对齐 |
| 目标移动 | 受器/目标位移，`φ` 相对几何失效 | `RECOVER` 重定位目标，必要时 `BACKTRACK` |
| 证据冲突 | 阶段头与谓词冲突，`c_t` 低 | `HOLD` 一个 chunk，再观测 |
| 人靠近 | 人手进入工作区 | `HOLD`/减速，不与人争抢 |
| 连续失败 | 同一子目标失败 ≥k 次 | `RECOVER` 换原语；仍失败则 `SKIP`（仅独立子目标） |
| 时间不够 | 剩余时间 < 预估 | `SKIP` 独立子目标，锁已有步骤分 |

人类撤销分数：

```text
u_t = 1[φ_i(t-1)=1, φ_i(t)=0] · edit_t · (1 - hold_t)
```

- `edit_t`：GEO-RESIDUAL 的编辑残差（当前帧不能用机器人动作解释的变化）；
- `hold_t`：夹爪是否持有该物体；
- `u_t` 高 → 人类撤销；`v_t` 高 → 机器人滑移。

**安全**：检测到人手靠近时，Guard 优先 `HOLD`，不执行快速回撤/重抓；恢复动作限速、限幅、最多 k 次。人不和机器人抢同一个物体。

### 4.6 Anytime 子目标调度：先锁步骤分，再冲成功率

排名先看成功率，成功率相同看步骤分。所以目标不是「所有步骤都做」，而是：

```text
max_π  E[Y] + λ·E[Σ w_i·φ_i/100] - μ·E[collision]
s.t.   T ≤ 180s
```

`λ` 小（步骤分是 tie-breaker），但不能为 0：当成功率已经很低时，锁步骤分是唯一收益。

调度器用贪心指数：

```text
I_i = w_i · P_i / max(t_i, ε)
```

- `P_i`：当前阶段成功概率（StageHead + 谓词）；
- `t_i`：预估耗时；
- 最后一步/高权重步骤加 bonus；
- 前置未完成的步骤不能被跳过；
- 独立子目标（水果1/2/3、碗1/2/3）可以重排/跳过。

时间策略：

- 前 60%：按图前向，优先恢复早期失败；
- 后 40%：若 `P(success)` 低，转向「高权重、可完成」的独立子目标；若 `P(success)` 高，集中冲最后一步；
- 超时前 20s：停止开新子目标，执行安全收尾/保持。

### 4.7 固定 chunk 内的阶段条件化执行

修正第 12 轮：`action_chunk_size` 固定，不能逐阶段变。做法：

- 全局 `T_a=5`（或 3/8，按 RTT 实测）；
- VLA 内部仍规划 30 步；policy 每次返回 5 步；
- 阶段条件化**速度因子** `σ(s)`：接触/插入/拉链阶段 0.4–0.7，运输阶段 1.0–1.2；
- 阶段条件化**伺服增益** `K(s)`：接触阶段降法向增益，保留切向；自由空间用 PBVS；
- 阶段条件化**保持/回退**：`HOLD` 时返回安全保持 chunk；`BACKTRACK` 时用上一阶段的恢复原语，不是简单反向播放动作。

这保持单模型合规，也不违反固定 chunk。

### 4.8 风险/情感调制：无音频的「情感」

`z_t` 的五个维度调制：

- `risk` 高 → 降速、增置信阈值、优先 HOLD；
- `urgency` 高 → 跳过独立子目标、缩短 VERIFY；
- `frustration` 高 → 换恢复原语、放弃当前子目标；
- `trust` 低 → 更多依赖谓词/Guard，少依赖 VLA 开环；
- `confidence` 低 → 增加一次观测/VERIFY，不盲目前进。

可选离线增强（P3，低优先）：用情感 TTS 生成多样化语言指令做数据增强；但任务指令固定、简单，收益低，不作为主线。

## 5. 四个可验证创新点

### C1 · StageGraph + StageHead：阶段先验是否比纯 VLA 更早发现「走错阶段」？

- 假设：StageHead 宏阶段 F1 ≥0.80，进度 MAE ≤0.12；比纯 VLA 的隐式进度更早 0.3–0.5s 发现阶段错误。
- 实验：离线 32 任务留出集；单任务通道 5 任务。
- 门：G1/G2。

### C2 · 可逆 Guard + 人类撤销检测：回退是否真的比「继续执行」涨点？

- 假设：在合成/真机 undo 注入下，恢复成功率 ≥60%，误触发 ≤5%，检测延迟 ≤300ms。
- 实验：数字孪生注入 T19/T16/T14/T27 的 undo；真机单任务 5 次 A/B。
- 门：G3/G4。

### C3 · Anytime 调度 + 风险调制：180s 内是否能把步骤分变成成功率？

- 假设：在固定 180s 下，步骤分 +5–10，超时率不升；独立子目标跳过不伤成功率。
- 实验：单任务通道 + 全量干跑；消融调度 on/off。
- 门：G5/G6。

### C4 · 固定 chunk 内的阶段条件化伺服：接触阶段减速/降增益是否比全局固定增益更稳？

- 假设：接触阶段超调/滑移下降，整体成功率不回归；5 步执行优于 30 步。
- 实验：CHUNK-SERVO 的 G2/G7 复用。
- 门：G7。

## 7. 竞赛策略：320 trials 是投资组合

- 32 任务 ×10 次 = 320 trials；单次成功率的标准误约 2.4pp，别被 +1–2pp 的噪声骗。
- 单任务不计分通道是唯一敢做 A/B 的地方；先测 5 个代表任务，再全量。
- 工程优先级：**高权重、多步骤、带 undo 备注、接触密集**的任务优先：
  - T19 拉链、T16 毛巾、T14 药瓶、T17 文具、T27 碗、T29 手机、T10 插头、T26 网线、T12 锁、T23 球拍、T31 文具袋、T09 工具箱。
- 先交安全基线锁 tie-break；再交 REV-GUARD；每次提交保留回滚开关。
- 不把预览榜单的任务排名当难度表；只用官方步骤权重和 undo 备注做先验。

## 9. 风险与合规

### 9.1 单模型合规

官方规则：所有任务须基于**同一模型**完成，不得混合多个模型一起测试。合规模式：

- **C1 离线标注**：StageGraph/谓词只离线生成标签，线上只有 WLA；
- **C2 确定性控制器**：Guard/Scheduler/Servo 是几何/控制律，无学习权重；
- **C3 同 checkpoint 特征**：StageHead/谓词用 WLA 同一 checkpoint 的特征，不加载第二个模型。

禁止：加载第二个学习策略/残差网络/独立视觉编码器做在线决策。

### 9.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 阶段标签噪声 | StageHead 不准 | 160 帧人工校正；置信低回退谓词/VLA |
| 谓词误报/漏报 | 错误回退/跳过 | 多证据融合；置信阈值；只在刚体/高置信任务启用 |
| 人类撤销 vs 滑移混淆 | 错误恢复 | `hold_t` + `edit_t` + 运动残差三证据；先 HOLD 再判定 |
| 过度回退 | 时间浪费/振荡 | 最大回退次数；回退后必须 VERIFY；冷却时间 |
| 人手安全 | 碰撞 | 人手检测即 HOLD/减速；恢复限速；不与人争抢 |
| 目标物消失 | 无法完成 | RECOVER 重定位；仍失败则 SKIP/放弃该子目标 |
| 官方步骤语义歧义 | 图错 | 以 `score_steps` 为准；重复物体用偏序；单任务通道验证 |
| 固定 chunk 与阶段冲突 | 接触段仍开环 | 5 步执行 + 阶段降速/降增益；不逐阶段改 chunk |
| 榜单合成 | 误判难度 | 只当预览；用单任务通道测 |
| 合规解释 | 被判第二个模型 | C1/C2/C3；材料写清；Guard 无学习权重 |

## 10. 一句话押注

**用官方 94 个得分点编译一张可逆阶段图，用同一 WLA checkpoint 的阶段头做进度先验，用任务引导谓词做可验证证据，用确定性 Guard 在人类撤销时回头、在卡住时重试、在时间不够时换子目标——把「最后 3 厘米」升级为「每个得分点都闭环」。**

# 灵感循环第 1 轮产物（状态文件第 13 轮）· REV-GUARD 技术报告

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是灵感循环第 1 轮（状态文件第 13 轮）想法区「REV-GUARD」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是把它们从观测层/执行层接到阶段层。

## 0. 结论与边界

### 0.1 一句话结论

官方 32 个任务一共 **94 个结构化得分点**，且「人为干扰」泛化里大量是**撤销/回退**（拉链拉开、毛巾翻开、盖子拧回、碗拿走、插头拔起）。这意味着当前 VLA 的核心缺口不只是「最后 3 厘米」，而是**阶段失明**：它没有显式的官方步骤状态，也没有「完成态被破坏」的回退机制。REV-GUARD 用官方 94 步编译可逆阶段图，在同一个 WLA checkpoint 上加阶段头，用任务引导谓词做证据，用确定性 Guard 做前向/回退/重试/跳过，用 anytime 调度在 180s 内先锁步骤分、再冲成功率。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、任务 JSON、排行榜 JSON 直接核实 | 32 任务/94 步、官方权重、人为干扰备注、API 无音频、33,276 eps、WLA 6B/30 步 |
| B | 我们在公开数据/网页上做的分析，可复现 | 榜单 `step~success` 回归、跨模型任务相关、腕部内参修正 |
| C | 设计假设，需 G0–G8 验证 | 阶段头 F1≥0.80、undo 恢复≥60%、步骤分+5、5 步执行优于 30 步 |

### 0.3 本轮不做什么

- 不做语音情绪识别/情感 TTS；数据无音轨，API 无音频。
- 不做完整 4D 场景图/第二个分割模型；只做任务引导的 2–5 个谓词。
- 不做逐阶段改 `action_chunk_size`；API 是提交级固定值。
- 不从零训 6B/14B VLA/WAM；用官方 WLA Base 做 action-head 微调。
- 不做 32 个任务各一个策略；违反单模型规则。
- 不做第二个学习 verifier/恢复策略；StageHead 与 WLA 同 checkpoint。
- 不做 30Hz 广域网伺服；固定 5 步执行 + 阶段条件化增益。
- 不做 6D 物体位姿网络；用相对位姿 + 局部谓词。
- 不做力/触觉闭环；API 没有。
- 不把预览榜单的任务排名当实测难度；只用官方步骤权重和 undo 备注做先验。

### 1.1 赛事与规则（A）

官方参赛手册（飞书 docx，通过 `r.jina.ai` 抓取；稳定拿到 §1.1–§2.2，后续章节可能截断，最终以官方页面为准）：

| 项 | 规则 |
|---|---|
| 模型 | 所有任务须基于**同一模型**完成，不得混合多个模型一起测试；模型类型不限（World Model、VLA 均可） |

### 1.2 提交 API（A）

提交模板 README（2026-10-31 复核）：

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640** |
| 本体 | 双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str` |

| 共享动作 | `action.left_gripper [1]`、`action.right_gripper [1]`、`action.pivot [7]` |

| token | `metadata.token` 握手校验一次；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile、audio** |
| 监控 | 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分 |

**关键推论**：

- `action_chunk_size=30`、控制频率 30Hz 时，一次 `get_action` 之后有 **1 秒开环执行**；chunk 内没有新观测，也没有打断机制。
- 不能按阶段改 chunk 长度；只能全局选一个 `T_a`，在 chunk 内做阶段条件化的速度/增益。
- 控制频率未在 README 中写死；本报告默认 30Hz，必须在单任务通道实测。

取证分析（B）：

1. `leaderboard_data.json` 的 `generated_from` 是 `"gen_leaderboard.py"`。
2. 对 8 个模型 ×32 任务做 `step_score ~ success_rate` 回归，**R² > 0.999999，最大残差 <0.006**；每个模型斜率不同，形式是 `step ≈ k_model × success`。这不是实测步骤分，是脚本生成的线性缩放。
3. 详情页 `details.html?model=MolmoAct2&user=DexHacker` 的 32 个任务视频全部是「测试视频占位，后续可替换为真实视频文件」。
4. 8 个模型的 32 维任务成功率两两相关，**平均 off-diagonal 相关系数约 0.098**；真实任务难度应让不同模型正相关。
5. 每任务只有 10 次 trial，但成功率出现 27.29%、27.85%、38.43% 等非 10% 整数倍；真实 10 次 trial 只能是 0/10、1/10、…、10/10。

**结论**：29.7% 只能当「赛事方预览上限/难度信号」；不能当 SOTA、任务难度表或失败分布。真实步骤分/失败分布必须用单任务不计分通道测。

2. 同一 checkpoint 内的阶段头，不是外部 verifier/第二个模型；
3. 反向边 + 人类撤销检测 + anytime 子目标调度，不是只做前向恢复；
4. 固定 API chunk 内的阶段条件化执行，不是改 chunk 长度或加第二个策略。

## 3. 问题形式化

### 3.1 官方评分作为 reward machine

任务 `τ` 的官方步骤 `s_1…s_n`，权重 `w_i`，`Σ_i w_i = 100`。定义完成谓词：

```math
\phi_i: \mathcal{O} \to \{0,1\}, \quad i=1\ldots n.
```

步骤分与成功：

```math
p_t = \frac{1}{100}\sum_{i=1}^{n} w_i\,\mathbf{1}[\phi_i(o_t)=1],
\qquad
Y = \mathbf{1}\left[\bigwedge_{i\in \mathcal{I}_{\mathrm{req}}} \phi_i(o_T)=1\right].
```

排名先比 `E[Y]`，再比 `E[p]`。所以策略目标不是单纯 `max E[Y]`，而是：

```math
\max_{\pi}\ \mathbb{E}[Y] + \lambda\,\mathbb{E}[p] - \mu\,\mathbb{E}[\text{collision}],
\qquad \lambda \ll 1,
```

subject to `T ≤ 180s`。`λ` 小，但在成功率低时步骤分是唯一收益。

### 3.2 可逆阶段图

```math
G_\tau = (V, E_f, E_b, E_r, E_s, w, \phi, \rho).
```

- `V = {v_0…v_n}`：稳定阶段；
- `E_f`：前向边 `v_{i-1}→v_i`，当 `φ_i=1`；
- `E_b`：反向边 `v_i→v_{i-1}`，当 `φ_i` 从 1 变 0；
- `E_r`：重试边 `v_i→v_i`，滑移/没抓住；
- `E_s`：跳过边，仅独立子目标；
- `w_i`：官方权重；
- `φ_i`：谓词；
- `ρ_i`：恢复原语（重抓/重对齐/重插/重拉/重定位）。

**偏序**：重复物体不强制全序；用对象级谓词。前置依赖强制前向边。这样既尊重官方步骤，又允许演示中的合理顺序变化。

### 3.3 阶段失明与可辨识性

VLA 策略 `π(a|o,l)` 没有显式 `s_t`；StageHead 估计：

```math
q_t = P(s_t \mid o_t), \quad r_t = P(\text{progress}\mid o_t), \quad c_t = \text{confidence}.
```

谓词给证据 `φ_i(o_t)`，融合：

```math
P(\phi_i=1 \mid o_t, h_t) \propto P(\phi_i=1 \mid o_t)\,P(\phi_i=1 \mid h_t).
```

可辨识性条件（与第 12 轮一致，扩展到阶段）：

1. 目标/受器在头部双目或腕部视野内；
2. 深度/视差有效（双目 ROI 有效像素 ≥70%，或腕部特征 inlier ≥15）；
3. 标定误差在门限内（重投影 ≤5px）；
4. 谓词置信/阶段置信高于阈值；
5. 任务/阶段属于可验证的刚体/半刚体接触类。

任一条不满足 → 回退 VLA 开环或 HOLD，不硬触发回退/跳过。

### 3.4 Anytime 目标

在时间预算 `B=180s` 下，选择子目标序列 `π`：

```math
\max_{\pi}\ \mathbb{E}[Y] + \lambda\,\mathbb{E}\left[\sum_i w_i\phi_i/100\right]
```

用贪心指数近似：

```math
I_i = \frac{w_i\,P_i}{\max(\hat{t}_i,\epsilon)} + \beta\,\mathbf{1}[i=\text{final}].
```

前置未完成不可跳过；独立子目标可重排/跳过；最后 20s 不再开新子目标。

## 4. 系统设计

### 4.1 总架构

```text
官方 tasks_v2/<slug>/info.json（32 任务 / 94 步 / 权重 / 人为干扰备注）
        │
        ▼
StageGraph Compiler（离线，确定性）
  ├─ 步骤→谓词 DSL
  ├─ 前向/反向/重试/跳过边
  ├─ 权重 w_i、恢复原语 ρ_i
  └─ 任务图 G_τ
        │
        ▼
Per-port GuardRuntime（CPU，确定性）
  ├─ StageHead（同一 WLA checkpoint）→ q_t, r_t, c_t
  ├─ SceneProbe（任务引导谓词）→ φ_i, uncertainty
  ├─ Guard 自动机 → FORWARD / HOLD / BACKTRACK / RETRY / SKIP / RECOVER
  ├─ Anytime Scheduler → 下一个子目标
  └─ Stage-conditioned Servo → σ(s), K(s)
        │
        ▼
Shared WLA server（GPU）：30 步规划，固定 5 步执行
```

- 每个端口一个 `GuardRuntime`，独立 `reset()`、独立图状态、独立计时。
- 共享 WLA server 用 session ID 区分端口；权重只有一份，不违反单模型。
- StageHead 与 WLA 同一次前向/同一 checkpoint；Guard/Scheduler/Servo 是 CPU 控制器。
- 数字孪生只做 undo 注入/标定/压力测试，不训练大策略。

### 4.2 StageGraph DSL / Compiler

DSL 示例：

```yaml
task: T19
steps:
  - id: 1
    weight: 50
    predicate: upright(bag)
    recovery: [push_upright, regrasp]
  - id: 2
    weight: 50
    predicate: zipped(bag)
    recovery: [regrasp_zipper, pull_zipper]
edges:
  - {from: 1, to: 2, type: forward, when: "upright(bag)"}
  - {from: 2, to: 1, type: backward, when: "not zipped(bag)"}
  - {from: 2, to: 2, type: retry, when: "slip(zipper)"}
```

编译器：

1. 解析 `score_steps`，抽动词/对象/受器；
2. 动词→谓词模板；
3. 重复物体用对象级谓词 + 偏序；
4. 前置依赖加强制前向边；
5. 从 `human_*_note` 抽 undo 类型，补反向边；
6. 权重取官方分数；
7. 人工审 94 谓词；
8. 输出 `G_τ` 和恢复原语表。

动词映射：

| 官方动词 | 谓词模板 | 恢复原语 |
|---|---|---|
| 抓/夹 | `grasped(x)` | 重抓/重对齐 |
| 放/放入 | `in(x,y)` | 重新放置 |
| 挂 | `hanging(x,y)` | 重挂 |
| 叠/堆叠 | `on(x,y)` / `stacked(x,y)` | 重新叠 |
| 插 | `inserted(x,y)` | 重对齐/重插 |
| 拔 | `removed(x)` | 重新夹住/拔出 |
| 拉上 | `zipped(x)` | 重抓拉链头/重拉 |
| 打开/盖上 | `open(x)` / `closed(x)` | 重抓把手/重盖 |
| 拧 | `rotated(x)` | 重抓/反向拧 |
| 摆正 | `upright(x)` | 推正/重摆 |

### 4.3 StageHead

- 输入：WLA 的 VLM/DiT 特征 + 本体状态（EE、夹爪、lower_body）。
- 输出：
  - `q_t`：8 类宏阶段（approach / align / grasp / transport / insert-or-place / manipulate / verify / recover）；
  - `r_t`：进度 `[0,1]`；
  - `c_t`：置信 `[0,1]`。
- 结构：2 层 MLP（hidden 512）+ 可选 cross-attention；<5M 参数。
- 训练损失：

```math
\mathcal{L} = \mathcal{L}_{\mathrm{action}}
+ \alpha\,\mathrm{CE}(q_t, y^{\mathrm{stage}})
+ \beta\,\mathrm{MSE}(r_t, y^{\mathrm{prog}})
+ \gamma\,\mathrm{ECE}(c_t).
```

- 标签：成功演示自动分割（速度/夹爪/接触变化）+ 160 帧人工校正（32×5）。
- 资源：冻结 VLM，只训 DiT action head + StageHead；24GB。
- 合规：同一 checkpoint、同一次前向；不是第二个模型。
- 回退：联合训练不稳定 → 冻结 VLM 特征 + 线性 probe；仍是同一 checkpoint 的附加头。
- 可选：94 路辅助头（数据足够时），但默认 8 类 + 进度更稳。

### 4.4 SceneProbe

谓词表（示例）：

| 谓词 | 证据 | 失败模式 |
|---|---|---|
| `grasped(x)` | 夹爪闭合 + 物体随夹爪运动 + 腕部 ROI | 滑移、透明物体 |
| `in(x,y)` | 物体中心在受器 ROI 内 + 深度顺序 | 遮挡、反光 |
| `on(x,y)` | 堆叠接触 + 相对高度 | 变形、透明 |
| `inserted(x,y)` | 插头/网口相对位姿 + 插入深度 | 遮挡、细线 |
| `zipped(x)` | 拉链头位置 + 齿合线 | 布料变形 |
| `open(x)` / `closed(x)` | 盖子角度/边缘 | 反光、透明 |
| `upright(x)` | 物体主轴与重力对齐 | 对称物体 |
| `removed(x)` | 物体从原 ROI 消失 + 夹爪持有 | 人手遮挡 |

实现：

- 头部双目：局部 ROI 视差/深度 + 颜色/边缘；
- 腕部：夹爪-物体相对运动、拉链/网口局部特征；
- 本体：EE 位姿、夹爪开合、关节位置（辅助）；
- VLM 特征：同 checkpoint encoder 做开放词汇匹配（不加载第二个模型）；
- 输出 `φ_i` + `uncertainty`；
- 校准：数据集内参 + `state_d435`；真实机器人首次运行重投影检查；置信低回退 VLA。

### 4.5 Guard 自动机

状态：

```text
FORWARD   正常执行当前阶段
VERIFY    到达阶段边界，等谓词确认
HOLD      人靠近/证据冲突，暂停
BACKTRACK 完成态被破坏，退回上一个稳定态
RETRY     同一阶段滑移/没抓住，重试
RECOVER   目标物消失/受器移动，重定位或放弃
SKIP      独立子目标卡住且时间不够
DONE      成功/时间到
```

转移表：

| 当前 | 触发 | 条件 | 下一状态 | 动作 |
|---|---|---|---|---|
| FORWARD | 阶段完成 | `φ_i=1` 且 `c_t` 高 | VERIFY | 等一个 chunk 确认 |
| VERIFY | 确认完成 | `φ_i=1` 连续 2 帧 | FORWARD | 更新进度 |
| VERIFY | 证据冲突 | `φ_i` 抖动/`c_t` 低 | HOLD | 再观测 |
| FORWARD/VERIFY | 人类撤销 | `φ_i` 1→0，`edit_t` 高，`hold_t=0` | BACKTRACK | 退回 `v_{i-1}`，重做 |
| FORWARD/VERIFY | 机器人滑移 | `φ_grasp` 1→0，`hold_t=1`，`motion_residual` 高 | RETRY | 重抓/重对齐 |
| FORWARD/VERIFY | 目标移动 | 受器/目标位移，`φ` 相对几何失效 | RECOVER | 重定位目标 |
| FORWARD | 人手靠近 | 人手进入工作区 | HOLD | 减速/停，不争抢 |
| RETRY | 连续失败 ≥k | `k=3` | RECOVER | 换原语 |
| RECOVER | 仍失败 | 目标消失/不可达 | SKIP | 仅独立子目标 |
| 任意 | 剩余时间 < 预估 | `T_left < \hat{t}` | SKIP/DONE | 锁已有步骤分 |

Undo/slip 分数：

```math
u_t = \mathbf{1}[\phi_i(t-1)=1,\phi_i(t)=0]\cdot edit_t\cdot(1-hold_t),
```

```math
v_t = \mathbf{1}[\phi_i(t)=0]\cdot hold_t\cdot motion\_residual_t.
```

`u_t` 高 → 人类撤销；`v_t` 高 → 机器人滑移；两者都低但 `φ` 抖动 → 传感器噪声，HOLD。

**安全**：人手靠近时优先 HOLD；恢复动作限速、限幅、最多 k 次；不与人争抢同一物体；目标物消失时先重定位，不盲抓。

### 4.6 Anytime Scheduler

- 估计每个子目标耗时 `\hat{t}_i`（演示统计 + 当前阶段头）；
- 成功概率 `P_i`（阶段头 + 谓词）；
- 指数 `I_i = w_i P_i / max(\hat{t}_i, ε)`；
- 最后一步/高权重步骤加 bonus；
- 前置未完成不可跳过；
- 独立子目标可重排/跳过；
- 前 60%：前向 + 恢复早期失败；
- 后 40%：若 `P(success)` 低，转向高权重可完成子目标；若高，集中冲最后一步；
- 最后 20s：安全收尾。

### 4.7 Stage-conditioned Servo

固定 `T_a=5`（或 3/8，按 RTT 实测）；VLA 内部 30 步规划；每次返回 5 步。阶段条件化：

```math
a_t = \sigma(s_t)\,a_t^{\mathrm{VLA}} + K(s_t)\,e_t,
```

- `σ(s)`：接触/插入/拉链 0.4–0.7；运输 1.0–1.2；
- `K(s)`：接触阶段降法向增益、保留切向；自由空间 PBVS；
- `e_t`：相对目标误差（DG-KEYFRAME）；
- `HOLD` 返回安全保持 chunk；`BACKTRACK` 用恢复原语，不简单反向播放；
- 不逐阶段改 chunk 长度。

### 4.8 Risk/Affect Modulation

| 维度 | 来源 | 调制 |
|---|---|---|
| `confidence` | StageHead `c_t` + 谓词置信 | 低 → 多 VERIFY/HOLD |
| `risk` | 谓词不确定 + `edit_t` + 人手距离 | 高 → 降速/停/恢复 |
| `urgency` | `T_left` / `\hat{t}` | 高 → 跳过独立子目标 |
| `frustration` | 同一子目标连续失败 | 高 → 换恢复原语/放弃 |
| `trust` | VLA 与 Guard 一致率 | 低 → 更多依赖谓词/Guard |

这不是情绪识别；是**风险敏感控制**。所有调制有上限/冷却，避免振荡。

### 4.9 与 CHUNK-SERVO / DG-KEYFRAME / GEO-RESIDUAL 的接口

- CHUNK-SERVO：提供 30 步规划/5 步执行、相对目标、确定性伺服；REV-GUARD 加阶段条件化 `σ/K`。
- DG-KEYFRAME：提供阶段级关键帧/相对位姿；REV-GUARD 用谓词重打分。
- GEO-RESIDUAL：提供 `edit_t`；REV-GUARD 加 `hold_t`/`motion_residual` 区分 undo/slip。
- FACT-VLA：提供阶段条件化 BC；REV-GUARD 用官方 94 步升级标签。

### 5.1 StageGraph compiler

```python
def compile_task(info):
    steps = info["score_steps"]
    nodes = [f"v{i}" for i in range(len(steps) + 1)]
    edges = []
    for i, step in enumerate(steps):
        phi = parse_predicate(step["zh"])
        edges.append(Edge(nodes[i], nodes[i+1], "forward", step["score"], phi))
        edges.append(Edge(nodes[i+1], nodes[i+1], "retry", 0, f"slip({phi})"))
    for note in info.get("generalization", {}).values():
        if is_undo(note):
            i = locate_step(note, steps)
            edges.append(Edge(nodes[i+1], nodes[i], "backward", 0, f"not {phi_i}"))
    return Graph(nodes, edges, weights=[s["score"] for s in steps])
```

### 5.2 StageHead training

```python
class StageHead(nn.Module):
    def __init__(self, d, k=8):
        super().__init__()
        self.trunk = nn.Sequential(nn.Linear(d, 512), nn.GELU(), nn.Linear(512, 512), nn.GELU())
        self.stage = nn.Linear(512, k)
        self.progress = nn.Linear(512, 1)
        self.conf = nn.Linear(512, 1)

    def forward(self, feat):
        h = self.trunk(feat)
        return (self.stage(h).softmax(-1),
                self.progress(h).sigmoid(),
                self.conf(h).sigmoid())
```

```python
loss = action_loss(pred_a, gt_a)
loss += alpha * CE(stage_logits, stage_label)
loss += beta * MSE(progress, progress_label)
loss += gamma * ECE(conf, correct)
```

### 5.3 GuardRuntime.get_action

```python
def get_action(self, obs):
    q, r, c = self.stage_head(obs)
    phi, unc = self.scene_probe(obs, self.graph)
    g = self.guard.update(phi, q, r, c, self.time_left)

    if g == HOLD:
        return self.safe_hold()
    if g == BACKTRACK:
        return self.recover(self.graph.prev_stage, obs)
    if g == RETRY:
        return self.retry(self.graph.cur_stage, obs)
    if g == SKIP:
        self.graph.skip_independent()
    return self.vla_chunk(obs, stage=self.graph.cur_stage)
```

### 5.4 Undo detection

```python
def classify_change(phi_prev, phi_now, edit, hold, motion):
    if phi_prev and not phi_now:
        if edit > theta_e and not hold:
            return "HUMAN_UNDO"
        if hold and motion > theta_m:
            return "ROBOT_SLIP"
    if not phi_prev and not phi_now and edit > theta_e:
        return "TARGET_MOVED"
    return "NO_CHANGE"
```
