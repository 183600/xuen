## 1. 直觉：先给画面，再给定义

### 1.1 「实时性」的第一性原理

大多数人把实时性理解成"每步延迟越小越好"。这个理解在 UniBot 里是**错的**，至少是**不完整的**。

**画面**：夹爪在 3 帧之内完成闭合，物体是否被夹住，取决于这 3 帧里动作是否还"看得见"物体的最新位置。若策略每 266 ms（s=8 步 × 33.3 ms）才换一次动作块，而推理又要 200 ms，那么在最坏情况下，机器人带着一条"300+ ms 前观测"生成的动作去完成接触——这已经不是慢，而是**在关键瞬间把闭环退化成了开环**。所以实时性的正确对象不是"平均延迟"，而是：

> **在每一个关键事件（接触、闭合、对齐、插入）发生时，被执行的动作用到了多新的观测。**

由此有三个时钟必须对齐：

1. **物理时钟**：接触与滑移发生在毫秒级，30 Hz 控制下只有 3–5 帧的容错窗口；
2. **推理时钟**：延迟 δ 是一个**分布**，不是常数；N 台真机共享后端时，各端口的延迟是**相关的**（队头阻塞、批处理、显存争用），不能按独立同分布处理；
3. **评测时钟**：一条 episode 约 43.7–45.2 s（teaser 数据），失败不是"慢了扣分"，而是**超时即 0 分**。

第二个反直觉点：**实时性通过"尝试预算"进入计分**。若同步推理在每块之间停顿，44 s 里可能有近 40% 的墙钟时间是在等模型；把这段等待变成重叠推理，省下的不是"速度分"（teaser 显示时长与成功几乎不相关，任务内 corr ≈ −0.011），而是**额外的重抓 / 重试机会**。而重试是成功率最直接的杠杆。于是实时性第一次可以被翻译成上一轮的唯一计分货币：**终态成功**。

第三个反直觉点：**chunk 长度/执行视界是"反应性—平滑性"的旋钮，而相位是"吞吐—尾延迟"的旋钮**。前者已经被 ACT/RTC 一类工作研究过；后者在"单后端、N 端口、远程接入"的 UniBot 赛制里是**新的、且几乎无人处理**的变量。

### 1.2 「虚拟仿真」的第一性原理

通常"虚拟仿真"指物理引擎 + sim-to-real。这个理解在 UniBot 里也**用错了地方**。

**画面**：我们真正害怕的"失败"有两类，它们的可仿真性完全不同：

- **A 类（工程失败）**：端口数不对、token 校验错、返回动作长度不合法、`reset()` 串扰、chunk 语义理解错、延迟尖峰导致动作下溢 → 直接判失败。这类失败**根本不需要物理引擎**，只需要一个**评测协议的逐位复刻**。它的 sim-to-real gap 是 **0**（同一份 client/server 代码路径）。
- **B 类（物理失败）**：抓不住、对不准、插不进、在未见物体上崩。这类失败需要物理/视觉仿真，但 sim-to-real gap 巨大，且**绝对成功率不可信**；能信的只有**排序**（哪个 checkpoint 更好、哪个分布偏移更致命）。

所以本轮把"虚拟仿真"拆成两种，并给它们**不同的信任等级**：

- **HDT（Harness Digital Twin，评测器数字孪生）**：仿真"协议 + 网络 + 时钟"，不仿真物理。零 gap、可复现、可注入延迟/抖动/掉包/时钟偏移。用于认证 A 类失败与实时性契约。
- **RCP（Rank-Calibrated Proxy，排序标定代理）**：SIMPLER 式 real-to-sim，仿真"物理 + 视觉"。有 gap，**只用于排序**，并用少量真机锚点标定 MMRV / 秩相关；过不了门槛就降级为压力测试，绝不用于调参。

这不是文字游戏：把两者混在一起（上一轮 IP-06 的隐患）会导致"用有 gap 的绝对分数去证明无 gap 的工程改动"，最后既浪费真机时段，又可能把方向调反。

### 1.3 两个灵感相乘

**实时性**（δ 分布、相位、陈旧度、尝试预算）× **虚拟仿真**（HDT 零 gap 认证 + RCP 只信排序）⇒ 本轮的三层结构：

```
契约层  HDT：把"时序契约"写成可执行、可认证、可注入故障的规范
          ↓ 提供 δ 分布 / 端口相位 / chunk 语义 / reset 隔离的 ground truth
策略层  DART：延迟条件化训练 + 重叠推理 + 事件触发重规划
          ↓ 输出 R(δ)：延迟响应曲线（不是单点延迟）
证据层  RCP + 真机锚点：只回答"这个改进在真机排序上是否成立"
```

一句话：**HDT 保证"不会因为工程事故丢分"，DART 保证"延迟不吞掉成功率"，RCP 保证"我们优化的方向在真机上仍然成立"。**

## 2. 为什么不是直接搬 RTC / SIMPLER

这是本轮最需要防守的"创新性"问题。

- **RTC 的假设是**：策略是 diffusion/flow 式 VLA，动作块在本地控制回路里执行，延迟主要来自模型本身。**UniBot 的假设是**：策略是一个远程 request/response 服务，延迟来自"模型 + 网络 + 评测端图像缩放 + N 端口批处理"，且**执行器的 chunk 语义未公开**。因此 RTC 的"freeze + inpaint"必须被重新表述为**带截止时间的、多租户的 chunk 调度**；训练时版本（模拟延迟 + 前缀条件化）反而更适合远程部署，因为推理端零额外开销。
- **SIMPLER 的假设是**：有一个可复现的真机 setup（Google Robot / WidowX），可以对齐视觉与控制器。**UniBot 的假设是**：只有 32 份官方 LeRobot 数据集与一个尚未公开细则的评测器。因此最有价值的"仿真"不是复刻物理，而是**复刻评测器**；物理代理只做排序。
- **本轮真正的新东西**是把"延迟"从噪声变成**可训练、可调度、可认证的设计变量**，并给出"什么时候锁相、什么时候错峰"的**可测量判据**（见 §3 的相图）。这在 RTC/SIMPLER 的原始设定里都不存在。

## 3. 本轮能算出来的东西（先给数，再谈方案）

### 3.1 时序预算的粗算：暂停时间 → 重试预算

取官方数据口径：Δt = 33.3 ms（30 Hz），s = 8（每块执行 266.4 ms），δ = 200 ms，T = 44 s。

| 策略 | 每块墙钟 | 占空比 | 44 s 内执行块数 | 等待时间 |
|---|---|---|---|---|
| 同步（执行完再推理） | 266.4 + 200 = 466.4 ms | 57.1% | ≈94 | ≈18.9 s |
| 重叠推理（δ < sΔt） | 266.4 ms | ≈100% | ≈165 | ≈0 s |

**若**单次重抓/重试（含定位、闭合、确认）约 6 s，则重叠推理换来的 ≈18.9 s 约等于 **3 次额外尝试**。在"单次成功概率 p≈0.3、尝试近似独立"的乐观模型下，成功率从 0.30 升到 1−0.7⁴≈0.76；即便考虑强相关与时间开销，量级也说明：**实时性不是速度项，而是成功率项**。这正是上一轮 P1（单一计分货币）想要的那条因果链。

> 注意统计陷阱：teaser 的"时长与成功无关"是在**已成功 episode** 上度量的。它说明"成功得快没有奖励"，但**不能**推出"等待不伤成功率"——等待伤的是**尝试次数**，而尝试次数只在失败边缘才显现。本轮把指标从 episode duration 改为 **time-to-decision** 与 **attempts-per-episode**。

### 3.2 多端口并发：相位是一个真实的实时性杠杆（机制仿真）

官方要求暴露连续端口 8765…8765+N−1、每端口独立跑完整交互 ⇒ 并发是"同步到达的突发"，不是平滑负载。我用一个显式的排队模型做了机制仿真（`exp/rt_twin_sim.py`，合成参数，不是真机证据）：每端口每 P=266 ms 请求一块；单请求服务时间 S ~ LogNormal(median=m, σ=0.40)；批处理服务时间 = S·(1+0.15·(b−1))；单后端 FIFO。

关键结果（完整表见 `exp/rt_twin_results.json`）：

| 单请求中位 m | N | 相位 | p99 延迟 | 下溢率（延迟 > P） |
|---|---|---|---|---|
| 30 ms | 32 | 同步 | 476 ms | 17.3% |
| 30 ms | 32 | 错峰 | 357 ms | **3.8%** |
| 60 ms | 8 | 同步 | 313 ms | 2.9% |
| 60 ms | 8 | 错峰 | 299 ms | 2.3% |
| 90 ms | 8 | 同步 | 549 ms | **27.2%** |
| 90 ms | 8 | 错峰 | 616 ms | 38.8% |

读法不是"错峰总是更好"，而是一个**相变**：

- 当单请求很便宜（m=30 ms）时，系统不是批处理受限，**错峰**显著降低尾延迟与下溢（N=32 时下溢 17.3% → 3.8%）；
- 当单请求很贵（m=90 ms）时，**锁相/批处理**才是可行的前提（同步 27.2% vs 错峰 38.8%），因为错峰把一次大 batch 拆成 N 次小 batch，边际成本吃掉全部收益；
- m=60 ms 是交叉区，两者接近。

**判据**：先用 HDT 测出真实的批处理曲线 B(b) 与单请求分布，再决定"锁相"还是"错峰"。这把"实时性"从"调低延迟"变成了"**整形到达过程**"——而这恰好是我们可以通过 `action_chunk_size` / 执行视界 s / 全局节奏器部分控制的。

### 3.3 对上一轮结论的修剪

- **保留**：IP-02（抓握确认）、IP-03（工程确定性）、IP-06 的信息价值。
- **升级**：IP-03 → **DART**（延迟条件化 + 重叠 + 事件触发）；IP-06 → **HDT + RCP** 双层。
- **延后**：IP-04（在线适配）、IP-05（姿态先验）、IP-07（双动作空间）。理由：它们都依赖"先有一个可信的时序与评测底座"；在 HDT/RCP 未跑通前推进，等于在流沙上盖楼。

## 4. 研究问题（Q6–Q10）

- **Q6（执行语义）**：官方 client 到底如何执行 chunk（严格固定长度？插值？每块是否重置控制器/滤波器？返回长度可否小于 `action_chunk_size`？）——能否用 HDT 做到与官方 example **逐条消息等价**？
- **Q7（节奏最优）**：给定 δ 分布、N、批处理曲线 B(b)，最优的 (s, 相位策略) 是什么？锁相与错峰的临界条件能否写成可测量判据？
- **Q8（延迟不变性）**：能否训练出对 δ **平坦**的策略（R(δ) 在 +200 ms 内下降 ≤1 分），且不牺牲 δ=0 时的精度？代价是训练算力还是动作多样性？
- **Q9（事件触发）**：事件触发重规划的**信息价值**（VoI）何时为正？触发阈值能否从 HDT 与少量真机数据估计，而不是拍脑袋？
- **Q10（代理有效性）**：RCP 的排序相关性在"未见物体"轴上是否仍然成立？如何用最小真机锚点**检测失效**（而不是假设它有效）？

## 5. 设计原则（在 P1–P6 之上新增 P7–P9）

- **P7（双仿真分层信任）**：协议级（HDT）零 gap，可信到"逐消息"；物理级（RCP）只信排序，不信绝对分数。两者的产物分开命名、分开报告，**禁止混用**。
- **P8（延迟是一等公民）**：任何策略改动都必须报告 **R(δ)** 曲线，而不是单点延迟。只报 `p99` 不报 δ 依赖的结论视为不完整。
- **P9（反脚本化）**：平滑只作用于 chunk 边界与速度残差，不改条件动作分布的均值与熵；用"非退化性"约束（动作熵、对观测的互信息）防止被"动作统计规律性"审计误判为脚本。

## 6. 最小可提交闭环（MVP）与退化链

**MVP = HDT（协议孪生 + 故障注入） + DART（重叠推理 + 训练时延迟条件化） + R(δ) 认证 + 通用 VLA 基线。**

不把 IP-01（技能路由）放进本轮 MVP：它是最大红利，但与实时层的交互项（专家切换本身引入延迟与抖动）会污染归因；等 HDT 能稳定测出"时序增量"后再叠加。

**严格退化链（任一环不可用 ⇒ 行为回退，不漂移）**：

- **L0** HDT 与官方 client 差分测试不一致 ⇒ **关闭一切时序优化**，只用官方 example 手工体检（端口 / token / reset / 长度）。
- **L1** 重叠推理不可用（线程 / 显存 / 框架限制）⇒ 退回短执行视界 + 固定 pause，但**仍报告 R(δ)**。
- **L2** 延迟条件化训练不可用 ⇒ 退回推理时 RTC 式前缀条件化（有额外推理开销，需重新测预算）。
- **L3** 事件触发不可用 ⇒ 退回固定 cadence，不触发。
- **L4** RCP 标定失败（MMRV/秩相关不达标）⇒ 只保留 HDT + 真机 A/B，物理代理降级为压力测试。
- **L5** 整条新链路失效 ⇒ 退回**纯基线策略**（永远保留一份能跑通、可信度合规的最小提交）。

## 7. 预期贡献（可验收）

1. **HDT**：一个与官方 client 逐消息等价的协议级数字孪生，能认证端口、token、reset 隔离、chunk 语义、延迟注入；把"A 类工程失败"从"提交后才知道"变成"本地可复现"。
2. **DART + R(δ)**：把延迟从噪声变成设计变量，给出延迟响应曲线与延迟不变性指标 DI；目标是在 +200 ms 注入下成功率下降 ≤1 分（参考 RTC 的鲁棒性形状，不照搬其数字）。
3. **相位相图**：给出"锁相 vs 错峰"的临界判据与跨端口节奏器（cadence controller），并证明它只改到达过程、不改策略分布。
4. **RCP 的失效检测**：不只报告相关性，还给出"在哪个 OOD 轴上失效"的诊断（MMRV + 分轴秩相关）。
5. **实时性的计分翻译**：把"暂停时间 → 尝试预算 → 成功率"写成可检验的因果链与预注册实验。

## 8. 本轮最大风险

## 0. 本轮结论摘要

**一句话路线**：把"实时性 × 虚拟仿真"编译成一条**时序栈**——

```
契约层  HDT：协议/网络/时钟的逐消息孪生（零 gap，认证 A 类失败）
   ↓
策略层  DART：延迟条件化训练 + 重叠推理 + 事件触发重规划（把 R(δ) 压平）
   ↓
证据层  RCP：物理代理只信排序（MMRV / 秩相关），不信绝对分数
```

**为什么是这个组合（四条依据）**：

| 依据 | 数值 / 事实 | 推出的设计 |
|---|---|---|
| 官方采集 per-step 延迟及其波动、动作统计规律性，并据此评估可信度 | 来自提交 README（第 1 轮已核实） | 实时性是**被审计的契约**，不是隐藏技巧 → HDT + ARC |
| 44 s episode、s=8、δ=200 ms 时同步推理占空比仅 ≈57% | 粗算：44 s 内约 18.9 s 在等模型 | 实时性通过**尝试预算**进入计分 → DART + E632 |
| RTC：重叠推理 + 前缀 inpainting 在 +200 ms 注入下保持吞吐（真实机器人任务） | arXiv 2506.07339 / NeurIPS 2025 | 延迟可被"压平"而不是只被"降低" → DART 的训练/推理双形态 |
| SIMPLER：视觉对齐 + SysID 的仿真在策略**排序**上与真机强相关（Google Robot 平均 Pearson≈0.92、MMRV≈0.056） | CoRL 2024, Table I | 物理仿真只用于**排序与压力测试**，不用于绝对分数 → RCP 的分层信任 |

## 2. 创新点详述（IP-09…IP-14）

### IP-09 · HDT：评测器数字孪生（P0）

- **动机**：官方明确会采集 per-step 延迟与动作统计；但"chunk 如何执行、是否插值、返回长度是否必须等于 `action_chunk_size`、`reset()` 是否重置控制器、端口如何隔离"这些**执行语义**并没有在 README 里给出可执行答案。任何在这些语义上"猜"的优化，都可能在大考时变成 0 分。
- **与现有方案的差异**：别人做"物理仿真"；我们做**协议仿真**。HDT 复用官方 `run_client.py` / `run_server.py` 的消息层与状态机，只替换"机器人 + 物理"为"可编程执行器 + 虚拟时钟"。
- **技术可行性**：高。需要：(a) 锁定官方 client 的 commit hash；(b) 建立消息级差分测试；(c) 用虚拟时钟注入 δ、抖动、丢包、时钟偏移；(d) 用可编程执行器模拟"固定长度/插值/重置"三种语义。
- **所需资源**：无额外数据；1 名工程师约 1–2 周；CPU 即可。
- **落地步骤**：① 复刻 metadata 握手、token 双校验、`obs_delta_indices` 叠帧、`image_resize`；② 复刻端口分配与 `reset()` 生命周期；③ 加入虚拟时钟与故障注入；④ 对每种执行语义做"探针实验"（E622），把语义写成可执行断言；⑤ 用 1000 条随机 trace 与官方 client 做差分（E620）。
- **风险**：HDT 与官方 client 漂移 ⇒ 每次提交前重跑差分；官方更新协议 ⇒ 版本化 HDT；**HDT 通过 ≠ 物理成功**（见 L11，这是本轮最大风险的来源）。

### IP-10 · DART：延迟感知实时 chunk（P0）

- **动机**：同步 chunk 的停顿把 44 s 的 episode 变成 ~25 s 的有效执行；而接触/闭合/插入的容错窗口只有几帧。延迟不是"慢"，是"关键瞬间的开环"。
- **与现有方案的差异**：①**训练时**注入延迟并条件化在"已承诺动作前缀"上（training-time RTC 思路，推理端零额外开销）；②**推理时**若训练时形态不可用，退回重叠推理 + 前缀条件化（RTC 思路，推理端有开销）；③**截止时间兜底**：超预算时返回"上一块的安全延拓 + 减速标记"，保证动作合法（L12）。
- **技术可行性**：中–高。训练侧只需在动作专家输入加"前缀 + 延迟步数 d"条件，并对 d 做分布采样；推理侧需要异步 worker 与线程安全的前缀缓存。
- **所需资源**：数据 = 官方 32 数据集；算力 = 基线 +10–20%（延迟增广与短前缀训练）；接口 = 仍是单 `get_action`。
- **落地步骤**：① 在 HDT 上测 δ 分布（p50/p99）与执行语义；② 训练 `π(a|o, prefix, d)`；③ 推理异步化 + 前缀缓存；④ 截止时间兜底；⑤ 在 δ ∈ {0,50,100,200,400} ms 上测 R(δ)（E623/E624）。
- **风险**：① 前缀条件化在非 flow/diffusion 主干上收益有限 ⇒ 先做 A/B，不假设；② 异步化引入竞态 ⇒ 每端口前缀缓存隔离（L14）；③ 训练分布与真实 δ 不匹配 ⇒ 宽分布 + OOD δ 测试。

### IP-11 · ETR：事件触发重规划（P1）

- **动机**：并非每一帧都需要新鲜观测；真正需要的是**关键事件前的几帧**。固定 chunk 要么太短（调用爆炸），要么太长（关键瞬间开环）。
- **与现有方案的差异**：把"自适应 chunk"从**相位驱动**升级为**事件驱动**：用 IP-02 的抓握/相位隐变量估计"未来 s−m 步内发生接触/闭合/插入的概率"，再做**信息价值（VoI）**判断。
- **技术可行性**：中。触发器的输入全部来自现有观测；阈值可从 HDT 的故障注入与少量真机数据估计。
- **所需资源**：小；复用 IP-02 的检测器与相位分类器。
- **落地步骤**：① 定义关键事件集合（grasp closure / first contact / insertion / release）；② 训练/标定 hazard 模型；③ 用 ETR 规则替换固定执行视界；④ 记录触发率、误触发代价、节省的陈旧度。
- **风险**：误触发会导致抖动与调用爆炸 ⇒ 触发率硬上限 + 冷却时间；hazard 在未见物体上漂移 ⇒ 保守回退到固定节奏。

### IP-12 · RCP：排序标定代理（P1）

- **动机**：真机时段稀缺、官方榜单尚未正式发布；但"哪个 checkpoint 更好、哪个分布偏移更致命"必须有本地标尺。SIMPLER 的经验是：**绝对成功率不可信，排序可以很准**。
- **与现有方案的差异**：不追求"高保真数字孪生"，而是追求"**排序有效**"：视觉匹配（合成真实背景/纹理）+ SysID（从真实轨迹拟合控制器刚度/阻尼）+ 5 轴可控变体；用 MMRV 与分轴秩相关做门槛，而不是只看绝对成功率。
- **技术可行性**：中。官方 32 份 LeRobot 数据足以做 visual matching 与 SysID；难点在"未见物体"轴的真实锚点。
- **所需资源**：1×A100 数小时/轮；真机锚点每轮 2–3 个时段。
- **落地步骤**：① 统一解码管线；② visual matching + SysID；③ 构造 5 轴变体；④ 用真机锚点计算 MMRV/秩相关；⑤ **失效检测**：故意破坏一轴，看门槛是否报警（E631）。
- **风险**：排序在"未见物体"轴上反转 ⇒ 分轴门槛 + 失效即降级为压力测试；代理被用来调参导致过拟合 ⇒ P7 禁止用 RCP 绝对分数做奖励。

### IP-13 · CPC：跨端口节奏器（P1）

- **动机**：官方要求 N 个连续端口、每端口独立跑完整交互，且 N 未知、随机顺序。若所有端口同时请求 chunk，后端的批处理会让**尾延迟**在关键瞬间集中爆发；若完全错峰，又会牺牲批处理效率。请求时刻部分由我们的 `action_chunk_size` / 执行视界决定 ⇒ 这是一个**可控的调度变量**。
- **与现有方案的差异**：多数提交只做"共享后端 + 每端口独立状态"；我们把**到达过程**当作一等对象，给出"锁相 vs 错峰"的可测量判据（L10 + §7 相图）。
- **技术可行性**：高（纯调度）；需要全局节奏器与每端口相位偏移，不改变策略分布。
- **所需资源**：极小；需线程安全与公平性。
- **落地步骤**：① HDT 测批处理曲线 B(b)；② 计算 N_max^sync / N_max^desync；③ 实现相位锁定与错峰两种模式；④ 按实测 N 与 m 选择；⑤ 压测（E627）。
- **风险**：锁相会让所有端口"同时卡住"（相关故障）⇒ 限制锁相组大小 + 保留错峰回退；错峰在批处理受限时反而更差 ⇒ 用 L10 判据，不拍脑袋。

### IP-14 · ARC：时序审计与实时性证书（P2）

- **动机**：官方会把延迟波动与动作规律性纳入可信度。与其被动担心，不如主动产出一份**可重放、可导出**的证书。
- **与现有方案的差异**：不是"日志"，而是**可验证的断言集合**：p99 预算、下溢率、降级率、jerk 上界、reset 隔离、动作熵/MI 区间。
- **所需资源**：极小。
- **落地步骤**：① 埋点；② 断言；③ 一键重放；④ 与 E2E 结果一起提交。
- **风险**：过度平滑/限幅压低成功率 ⇒ 平滑只作用于残差与边界；动作熵有下限（L13）。

## 3. 符号与定义（U13–U24）

| 符号 | 含义 |
|---|---|
| `K` | 时序契约（Temporal Contract） |
| `δ` | 单次推理延迟（ms），`δ ~ Δ_N`（N 端口下带相关性的分布） |
| `d` | 延迟步数 `d = ⌊δ/Δt⌋` |
| `τ_t` | 决策陈旧度：被执行动作所用最新观测的年龄 |
| `R(δ)` | 延迟响应曲线：注入延迟 δ 时的期望成功率 |
| `DI` | 延迟不变性指数 |
| `φ_i` | 端口 i 的请求相位 |
| `B(b)` | batch 大小 b 时的服务时间 |
| `A` | 真机锚点集合 |
| `MMRV` | Mean Maximum Rank Violation（越小越好） |
| `H(·)` / `I(·;·)` | 熵 / 互信息 |

**定义 U13（时序契约）** `K = ⟨control_space, H, s, Δt, δ_budget, obs_aperture, phase_policy⟩`。`H` 为声明的 `action_chunk_size`，`s` 为每块实际执行的动作数（`s ≤ H`），`Δt=33.3 ms`，`δ_budget` 为 p99 延迟预算，`obs_aperture` 为各观测键的最大 `|obs_delta_indices|`，`phase_policy` ∈ {sync, spread, adaptive}。运行时任何偏离 `K` 的行为必须标记为 `degraded` 并计入审计（U24）。

**定义 U14（延迟与延迟步数）** `δ_t = t_ready − t_obs`，`d = ⌊δ/Δt⌋`。N 端口共享后端时，`δ_t` 不是 iid：`Cov(δ_i, δ_j) ≥ 0` 由队头阻塞/批处理/显存争用产生。

**定义 U15（决策陈旧度）** `τ_t = t − t_obs(a_t)`，其中 `t_obs(a_t)` 是**因果影响**被执行动作 `a_t` 的最新观测时间戳（由 chunk 的来源与执行时刻追踪）。这是实时性的真正状态变量。

**定义 U16（前缀条件化动作块）** `A_new = f_θ(o_t, A_prev[0:m], m=d)`，前 `m` 个动作与已承诺前缀一致（RTC 式 freeze+inpaint）；训练时把 `m` 作为随机变量采样，`m ~ p(d)`。

**定义 U17（延迟响应与不变性）** `R(δ) = E[success | 注入延迟 δ]`，在 `δ ∈ {0,50,100,200,400} ms` 上测；`DI = 1 − (R(200) − R(0)) / max(R(0), ε)`（越大越"延迟不变"）。

**定义 U18（尝试预算）** 给定 episode 预算 `T`、单次尝试墙钟 `c_a(δ)`，最大尝试数 `K(δ) = ⌊T / c_a(δ)⌋`；在"尝试近似独立、单次成功 `p`"的显式假设下 `P_success(δ) = 1 − (1−p)^{K(δ)}`。这是建模恒等式，不是事实主张。

**定义 U19（事件触发 / VoI）** 在决策点触发重规划当且仅当 `E[Δsuccess | 立即重规划] − c_replan > 0`，其中 `c_replan` 包含延迟/抖动代价；用 hazard `h_t`（未来 `s−m` 步内发生关键事件的概率）与陈旧度惩罚近似。

**定义 U20（HDT 协议等价）** 设官方 client 的协议状态机为 `C`，HDT 为 `H`。若存在关系 `R ⊆ Σ_H × Σ_C` 使得初始状态相关，且对每条合法消息 `m`，`(σ_H, σ_C) ∈ R ⇒ (δ_H(σ_H,m), δ_C(σ_C,m)) ∈ R`，则称 `H` 与 `C` 在消息字母表上**互模拟**。HDT 的**可靠性（soundness）**：`H` 报出的协议违规一定是真违规；**完备性**只对有限消息交错成立（需 fuzz/模型检验）。

**定义 U21（相位与批处理）** 端口 `i` 的请求时刻 `t_{i,k} = φ_i + kP`，`φ_i ∈ [0,P)`；`B(b) = S·(1 + k_b·(b−1))`。同步可行性：`E[B(N)] < P`；错峰可行性：`N·E[S] < P`。

**定义 U22（RCP 排序有效性）** 在锚点集 `A` 上，`MMRV(A)` 与 `Spearman ρ(A)` 达到预设门槛时，RCP 才可用于**选择**；否则只可用于**压力测试**。

**定义 U23（非退化性）** 对条件动作分布 `p(a|o)`，要求 `H(p(·|o)) ≥ ε_H` 且 `I(A;O) ≥ ε_I`；平滑核带宽 `h ≤ ĥ`，`ĥ` 为从数据估计的条件标准差。用于防止"过度平滑 / 脚本化"。

**定义 U24（时序审计向量）** `Audit = ⟨p50, p99, max, jerk_p99, underrun_rate, deadline_miss_rate, degrade_rate, reset_isolation_violations, action_entropy, mi_estimate⟩`；必须可由原始日志一键重放。

## 4. 推导（L8–L14）

**引理 L8（陈旧度上界）**
设 chunk 长 `H`、每块执行 `s` 步、控制器步长 `Δt`、推理延迟 `δ`、`d=⌈δ/Δt⌉`。
(a) 同步执行（执行完再推理）：`τ_max = δ + (s−1)Δt`。
(b) 重叠推理 + 前缀条件化：`τ_max ≤ δ + dΔt`；其中"新鲜段"（前缀之后的动作）的陈旧度 `≤ δ`，而"已承诺前缀"至多 `d` 步是旧的。
(c) 若 `d < s`（远程推理的典型情形：`d≈6, s=8`），则 `δ + dΔt < δ + sΔt` ⇒ 重叠推理严格降低最坏陈旧度；若 `s` 很小（`d ≥ s`），重叠的优势转为"消除停顿 + 连续"，而不是降低最大陈旧度。
**证明思路**：(a) 动作块由 `t−δ` 的观测生成，块内第 `k` 个动作的有效上下文最老为 `k=s−1`；(b) 新块在开始执行前完成推理，前缀之外的动作用到的最新观测年龄不超过 `δ`；前缀本身是上一块为"保证执行"而冻结的 `d` 步；(c) 直接比较两个上界。∎
**推论**：缩短 `s` 线性降低同步陈旧度，但增加推理需求；最优 `s` 由 L8 与 L10 的容量约束共同决定。**不要**把 RTC 宣传成"陈旧度 = δ"——它的准确收益是"新动作 ≤ δ + 前缀 d 步旧 + 无停顿"。

**引理 L9（尝试预算恒等式）**
同步停顿占空比 `ρ = sΔt/(sΔt+δ)`；可回收时间 `ΔT = T·δ/(sΔt+δ)`；额外尝试 `ΔK = ⌊ΔT/c_a⌋`。在 U18 的独立假设下，成功率增量为 `ΔP = (1−p)^{K_0} − (1−p)^{K_0+ΔK} ≥ 0`，且随 `δ` 单调增。∎
**意义**：这把"实时性"严格地翻译成了上一轮的唯一计分货币（终态成功），而不是虚构一个"速度分"。

**引理 L10（相位容量与尾延迟）**
设 `E[S]` 为单请求期望，`B(b)=E[S](1+k_b(b−1))`，`k_b∈(0,1)`，`P` 为 chunk 周期。
(a) 锁相（同步）可支撑端口数 `N_sync = 1 + (P/E[S] − 1)/k_b`；
(b) 错峰（每次 batch=1）可支撑 `N_spread = P/E[S]`；
(c) 因 `k_b<1`，恒有 `N_sync > N_spread` ⇒ **锁相扩大容量**；但在低负载区，错峰能**去相关**服务时间冲击，降低尾延迟。故"锁相 vs 错峰"不是容量问题，而是**尾风险问题**。
**代入**（`E[S]=1.083·m`，`k_b=0.15`，`P=266 ms`）：`m=30 → N_sync≈49, N_spread≈8`；`m=60 → N_sync≈22, N_spread≈4`；`m=90 → N_sync≈12, N_spread≈3`。∎
**推论（可执行判据）**：测出 `m, k_b, N` 后，若 `N > N_spread` 且 `N ≤ N_sync`，**必须锁相**；若 `N ≪ N_spread`，**优先错峰**以压尾；中间区用 A/B。

**引理 L11（HDT 的必要性而非充分性）**
若 HDT 与官方 client 在协议字母表上互模拟（U20），则 HDT 报出的 A 类（工程）失败在真机上必然发生；反之，HDT 通过**不蕴含**任何 B 类（物理）成功率。故 HDT 的通过率不能当作成功率，只能当作"不会因工程事故丢分"的下界认证。∎
**意义**：这是本轮对抗"最大风险"的形式化护栏。

**引理 L12（截止时间兜底的安全性）**
若超时兜底返回"上一块末动作的零速延拓（或限速延拓）"，且动作在关节/EE 限位内，则超时只会降低最优性，不会产生非法动作或协议违规；边界 jerk 的上界由延拓速度与 `Δt` 决定。∎
**意义**：任何"来不及"都不应变成"硬失败"。

**引理 L13（过度平滑不可能提高成功率）**
设平滑算子 `T` 在给定 chunk 的条件下与观测 `o` 独立。由数据处理不等式，`I(T(A);O) ≤ I(A;O)`；若任务成功依赖于动作对场景的条件信息，则过度平滑不能提高成功率，只会降低反应性。故平滑带宽必须受条件方差 `ĥ` 约束（U23）。∎
**意义**：把"动作看起来规律"与"动作有用"明确分开；反脚本化不是审美，是信息论约束。

**引理 L14（端口隔离）**
若共享状态仅为只读模型权重，且每端口的可变状态存于互不相交的键空间，则对任意端口 `p' ≠ p`，`reset(p)` 不改变 `p'` 的输出分布。∎
**意义**：这是可测试的不变量（E621），也是官方"每端口独立跑完整交互"的最低要求。

# ===== IP-10 + IP-11: DART + ETR 的统一策略服务 =====
class DAPTDPolicy:                      # 单 checkpoint、单 API
    def __init__(self, ckpt, N):
        self.model = load_single_checkpoint(ckpt)
        self.prefix = {p: None for p in range(N)}      # 每端口隔离（L14）
        self.etr = EventTrigger()                      # U19
        self.guard = DeadlineGuard(ms=105)             # L12

    def get_action(self, obs, port):
        d = self.etr.delay_steps(port)                 # U14
        s = self.etr.horizon(port, obs)                # U13/U15
        # 训练时已见 (prefix, d)；推理时零额外 inpainting 开销
        chunk = self.model.predict(obs, prefix=self.prefix[port], delay_steps=d, exec_horizon=s)
        chunk = self.guard.safe_extend(chunk, self.prefix[port])   # L12
        self.prefix[port] = chunk[:d]                  # 已承诺前缀
        return pack(chunk, s)
```

def should_replan(hazard, staleness, c_replan, delta_success):
    # hazard: P(未来 s-m 步出现接触/闭合/插入)
    p_miss = hazard * sigmoid((staleness - tau0) / k)

# ===== IP-13: 跨端口节奏器 =====
def choose_phase(n, m_single, k_b, P):
    n_sync = 1 + (P / (m_single * 1.083) - 1) / k_b   # 引理 L10
    n_spread = P / (m_single * 1.083)
    if n <= n_spread * 0.7:
        return "spread"        # 低负载：去相关，压尾
    if n <= n_sync * 0.9:
        return "lock"          # 批处理受限：锁相保容量
    return "lock+split"        # 超容量：锁相 + 拆后端/降分辨率
```

## 7. 本轮机制仿真结果（合成参数，不是真机证据）

脚本：`exp/rt_twin_sim.py`；结果：`exp/rt_twin_results.json`。模型：每端口每 `P=266 ms` 请求一块；`S ~ LogNormal(median=m, σ=0.40)`；`B(b)=S·(1+0.15(b−1))`；单后端 FIFO；`N ∈ {4,8,16,32}`；相位 ∈ {sync, desync, jitter}；24 seeds × 60 s。

| m (ms) | N | 相位 | p50 | p99 | 下溢率 |
|---|---|---|---|---|---|
| 30 | 32 | sync | 177.9 | 476.2 | 0.173 |
| 30 | 32 | desync | 105.5 | **356.8** | **0.038** |
| 30 | 16 | sync | 97.1 | 242.7 | 0.006 |
| 30 | 16 | desync | 59.5 | 154.5 | 0.000 |
| 60 | 8 | sync | 123.4 | 313.1 | 0.029 |
| 60 | 8 | desync | 119.4 | 299.3 | 0.023 |
| 60 | 16 | sync | 223.3 | 614.0 | 0.347 |
| 60 | 16 | desync | 214.2 | 627.6 | 0.339 |
| 90 | 8 | sync | 202.3 | **549.5** | **0.272** |
| 90 | 8 | desync | 233.7 | 615.5 | 0.388 |

**解读**：
1. 低负载/批处理便宜区（m=30）：错峰显著压低尾延迟与下溢（N=32 时 17.3% → 3.8%），因为同步会让所有端口同时承受同一批服务时间冲击。
2. 高负载/批处理昂贵区（m=90）：锁相是**容量前提**（27.2% vs 38.8%），因为错峰把大 batch 拆成 N 次小 batch，边际成本吃掉收益。
3. m=60 是交叉区，两者接近 ⇒ **不能凭直觉选，必须用 HDT 测 B(b) 后按 L10 判据选**。
4. 该仿真的服务端在积压时会把错峰请求重新合并成 batch，因此实际结果比"纯 desync 容量公式"更乐观；这也说明**真实调度器的批处理窗口**是关键未知量，必须由 HDT 实测。

> 该仿真的唯一目的是证明"相位是实时性杠杆，且方向随批处理曲线改变"；所有绝对数字依赖假设，不作为真机预测。

## 12. 本轮最值得押注的点

**押注 IP-09（HDT）作为第一优先级，IP-10（DART）作为第二优先级**：HDT 把"执行语义/端口/延迟"从传闻变成可复现实验，是整条实时性路线的**信任根**；DART 则把延迟通过"尝试预算"翻译成唯一计分货币（终态成功），是唯一能直接兑现为分数的时序杠杆。二者组合的风险最低、信息价值最高。

**最大风险（一句话）**：把 HDT 的"协议级零 gap"误当成"物理级可信"，于是我们把延迟、端口、chunk 边界全部认证到无可挑剔，却无法知道这些优化在未见物体上是否真的把成功率换回来了。
