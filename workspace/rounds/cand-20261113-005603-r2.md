# 本轮迭代（灵感循环 v3：「深度相机」×「可靠性」）—— 给 UIP 清单补上「感知可靠性」这条腿

> 承接上轮 v2（UIP-01′~15）。v2 的旗舰是「检测进度被撤回 → 重做」，但它默认了一件事：**验证器看得清**。本轮要回答更底层的问题：**验证器凭什么相信自己的眼睛？** 新核实的关键事实是：官方评测接口只传 4 路 RGB，**没有任何 depth 键**；头部是已校正双目（基线 58.25 mm，f≈282 px），腕部只有单目彩色（硬件侧 IR 双目基线 18 mm，但评测不传深度）。也就是说，深度必须自己算，而它恰好在最难的透明/反光/细长/无纹理物体上最不可靠。于是本轮的支点不是「换一个更强的深度模型」，而是把深度当作**带不确定性的测量**，把「知道自己不知道」变成可执行的策略。

**双目测深误差的杠杆**：`Z=fB/d` ⇒ `σ_Z=(Z²/(fB))·σ_d`。代入 `fB≈16.45 m·px`：

| 距离 Z | 视差 d | 1 px 视差误差 → 深度误差 | 0.3 px 亚像素 → 深度误差 |
|---|---|---|---|
| 0.3 m | 54.8 px | 5.5 mm | 1.6 mm |
| 0.5 m | 32.9 px | 15.2 mm | 4.6 mm |
| 1.0 m | 16.5 px | 60.8 mm | 18.2 mm |
| 1.5 m | 11.0 px | 136.8 mm | 41.0 mm |

**读表结论**：头部双目在 0.3–0.6 m 的桌面接触区够用，但一过 1 m 就迅速崩；而接触点还常被腕部/夹爪遮挡，并在透明/反光/细长物体上失去匹配纹理。**深度不是免费的，它是一张随位置、材质、视角变化的不确定度地图。**

## 1. 直觉：深度相机是「量具」，不是「相机」

普通相机回答「这里是什么颜色」；深度相机回答「这里离我多远」。后者是一个**测量**，不是一个事实。任何测量都有量程、分辨率、噪声和失效模式：双目在无纹理处靠不住，在透明/反光表面会把折射/反射当成真实距离，在细长物体上会因遮挡边界产生「飞点」，在远端因视差变小而误差平方级放大。更糟的是，接触密集操作的关键区域——夹爪与物体的接触点——恰好是遮挡最重、镜面反射最强、纹理最少的地方。因此，一个把深度当 ground truth 的策略，会在最关键的时刻**自信地错**。

可靠性工程给的直觉不是「把均值做得更好」，而是：**先定义什么算可信，再在不可信时主动补证据，最后为尾部风险留预算**。这正是本轮想移植到 UniBot 的东西：不是再训练一个更大的策略，而是给策略装一只「知道自己看不清」的眼睛，并把「看不清」转化为「换视角 / 重测 / 保守推进」的动作。

---

## 2. 两个灵感词的解读

1. **深度相机**：不是「再加一个传感器」（接口也不给深度），而是**把现有 RGB 重构成一台虚拟深度相机**。头部双目提供全局米制尺度（基线 58 mm，近场可用）；腕部单目提供接触区高分辨率但缺尺度；机器人自身的运动提供第三根「虚拟基线」——只要知道末端位姿，就可以把腕部相机在不同时刻的观测做多视图三角化。三者合起来，才是一台**可自检、可降级**的深度相机。
2. **可靠性**：不是单一指标，而是三层串联的必要条件：**感知可靠性**（逐像素深度是否可信）、**决策可靠性**（宣告 done/regressed 的误判率是否有上界）、**交互可靠性**（延迟尾部、抖动、端口隔离、动作规律性是否稳定）。任何一层失效，都会把「步骤分」变成尾部风险；所以可靠性应当被当作**预算**来分配，而不是当作一个布尔开关。

---

## 3. 严谨定义

### 3.1 观测与深度测量模型

单步观测记为

`o_t = (I_t^L, I_t^R, I_t^{wL}, I_t^{wR}, q_t, l)`

其中 `I^L/I^R` 为头部校正双目，`I^{wL}/I^{wR}` 为左右腕单目彩色，`q_t` 为关节/末端/夹爪本体感觉，`l` 为语言指令。深度不是观测，而是估计量：

`D̂(u,v) = f·B / δ̂(u,v)`

`δ̂` 为视差，`f` 为焦距（像素），`B` 为基线（米）。由一阶误差传播：

`σ_D(u,v) ≈ D̂(u,v)² / (f·B) · σ_δ(u,v)`

`σ_δ` 不应只取常数，而应由四类证据合成：匹配代价曲率（局部可辨识性）、左右一致性（遮挡/重复纹理）、时序残差（运动/压缩噪声）、纹理/饱和/镜面掩码（物理失效）。这一步给出的是**异方差**不确定度：近处小、远处大；有纹理处小、无纹理处大；漫反射处小、镜面/透明处大。

### 3.2 可靠性图与三值谓词

定义逐像素可靠性

`r(u,v) = P(|D̂(u,v) − D(u,v)| ≤ τ | evidence)`

`τ` 为任务允许的几何容差（例如插网线需要 2–5 mm，叠碗可以 10 mm）。给定风险水平 `α`，可信区

`T_α = {(u,v) : r(u,v) ≥ 1 − α}`

把几何谓词从二值升级为三值（Kleene 逻辑）。对测量 `D̂ ± kσ_D` 与阈值 `c`：

- 若 `D̂ + kσ_D < c`，谓词为 `true`；
- 若 `D̂ − kσ_D > c`，谓词为 `false`；
- 否则为 `unknown`。

复合谓词用 Kleene AND/OR 组合：`true` 需要所有支撑像素在可信区内且裕度超过 `kσ`；`false` 需要反例在可信区内且超过 `kσ`；其余一律 `unknown`。**关键规则：`unknown` 绝不等价于 `done`。** 这直接改变 v2 的状态机：验证器多了一个「拒绝表态」的输出，而拒绝表态会触发主动补测，而不是盲目推进。

### 3.3 运动双目与条件数

腕部单目没有第二视角，但机器人可以自己制造基线。设末端在时刻 `i,j` 的相机位姿为 `T_i,T_j`（由正运动学给出），对同一三维点 `X` 有投影 `u_i=π(T_i X)`。有效基线取垂直于视线方向的分量：

`b_eff = ||(I − ẑẑᵀ)(t_i − t_j)||`

视差角 `θ ≈ b_eff / Z`。三角化深度不确定度同形：

`σ_Z ≈ Z² / (f·b_eff) · σ_px`

因此「运动双目」的可靠性由三个量决定：**视差角是否足够大**、**特征跟踪是否稳定**、**三角化条件数 `κ` 是否可控**。定义

`r_kmv = 1[θ ≥ θ_min] · 1[reproj_err ≤ ε] · exp(−κ/κ₀)`

这就是把「机器人动一下」变成一个有明确误差模型的测量动作，而不是碰运气。

### 3.4 保形验证与误推进上界

深度学习的 softmax 置信度不是概率保证。要把「宣告 done 但实际没 done」的误推进率压到 `α` 以下，可用 split conformal / conformal risk control：在标定集 `{(o_i,y_i)}` 上定义单调损失

`ℓ_λ(o,y) = 1{在阈值 λ 下宣告 done 且 y = not_done}`

选择 `λ̂` 使标定集风险 `(1/n)Σℓ_λ ≤ α`（带有限样本修正）。在可交换性假设下，测试期误推进率的期望不超过 `α`。对 `regressed` 用另一个更保守的阈值（因为「误判被撤回→反复重做」的代价不对称）。这给的是**分布无关的上界**，比「模型说置信度 0.9」强得多。

### 3.5 可靠性预算

设子目标（计分步）`g=1..G`，分值 `v_g`，下游价值

`V_g = v_g + Σ_{h>g} v_h · P(reach h | g correct)`

总风险预算 `α_total` 按「价值越高、越靠近末步、越会级联」越保守来分配：

`α_g = α_total · (1/V_g) / Σ_h (1/V_h)`

时间预算 `T` 与延迟尾部约束 `P(τ > L_max) ≤ δ` 同时生效。是否值得补测，用价值信息（VOI）判断：

`acquire if E[Δscore | acquire] > λ_t · E[Δt]`

也就是说，**不是越谨慎越好，而是把谨慎花在期望收益最高的地方**。这为后面的「可靠性门控」提供了防止瘫痪的数学护栏。

### 3.6 交互可靠性

把远程交互也纳入同一框架：

- `R_int = P(τ_latency ≤ L_max)`（延迟尾部）；
- `J = p99(τ) − p50(τ)`（抖动）；
- `S = E||a_{t+1} − a_t||`（动作规律性/平滑度，需在合理范围内）。

可靠系统的目标不是「平均最快」，而是**尾部可控、抖动有界、动作不异常**。这与 README §6 的可信度口径直接对齐。

## 4. 瓶颈假设（本轮更新）

- **H1（最高杠杆）**：在接触密集任务上，**深度可靠性**而不是策略容量，才是步骤分验证的约束瓶颈；「检测到 unknown」的边际价值高于「把平均深度误差再降 10%」。
- **H2**：腕部单目 + 正运动学可以在接触点恢复毫米级米制深度；限制因素是可接受的运动幅度与时间预算，而不是算法本身。
- **H3**：保形/校准过的验证器能给出误推进率上界；未校准的 softmax 置信度不能，且会在透明/反光场景系统性过自信。
- **H4**：过度保守的门控会导致超时/瘫痪，反而丢步骤分；最优策略是**风险预算 + 强制推进兜底**，不是单一高阈值。
- **H5**：远程压缩、丢帧、时间戳错位、标定漂移会以「看不见的方式」污染深度；传感器完整性检查必须与感知算法同层设计。

## 6. 本轮最大风险

## 1. 旗舰深潜：UIP-01″ · RG-RV（Reliability-Gated Rolling Verification）

### 1.1 机制

动作块 `A=(a_1..a_{T_a})` 不整段盲执行。设 `action_chunk_size=k`，每个 chunk 边界用验证器 `V(o_t,l,g)` 判断当前子目标 `g` 的状态：

`{done, ongoing, fail, regressed, unknown}`

其中 `regressed` 来自 v2 的「反向撤回」证据；本轮新增 `unknown`：当几何谓词依赖的像素落在低可靠区，或几何裕度小于不确定度时，验证器**拒绝表态**。状态转移规则：

- `done`：仅在可信区内谓词为 `true`，且通过保形阈值（UIP-18）；
- `regressed`：仅在可信区内谓词由 `true` 翻为 `false`，且时序变化超过噪声；
- `unknown`：触发 UIP-17 主动补测，或 UIP-19 的保守推进；
- `fail`：可信区内谓词为 `false` 且不是「曾经 done 后被撤回」。

### 1.2 与 v2 的差异

v2 的 UIP-01′ 只有 done/fail/ongoing/regressed，默认验证器看得清；v3 把「看不清」提升为一等状态。这样做的收益是**双保险**：既减少「没做完却宣告 done」的假推进，也减少「被撤回却继续前进」的步骤分损失；代价是可能增加补测时间——由 UIP-19 的风险预算约束。

### 1.3 可行性

高。所有动作都在 `get_action` 内；`action_chunk_size`、`reset()`、图像输入均在接口内；深度由头部双目与腕部运动计算，不需要额外 obs 键。经典 SGM + 小型可靠性头可与主骨干共享，避免「多模型」合规歧义。

### 1.4 落地步骤

1. 逐任务写 2–5 个可观测子目标与几何谓词（与 §2 计分点对齐）；
2. 在 GSO-D 中渲染深度 GT，拟合深度噪声/失效模型，校准 `r` 与保形阈值；
3. 用 DRF-D 生成「撤回 + 深度失效」训练与测试数据；
4. 接入三值状态机与风险预算，先在 5 个代表任务上调参；
5. 真机预约时段做校准锚点，重估 sim-to-real 偏移。

### 1.5 风险

误判 `regressed` 会「反复重做」，误判 `unknown` 会「反复补测」→ 用 CSG-R 三重护栏（置信度门限 / 最大重做次数 / 延迟预算）与 RBG 的强制推进兜底。

## 2. UIP-16 · DRA（Depth Reliability Atlas）

### 2.1 直觉

深度图不是一张「距离照片」，而是一张「距离 + 误差」的地图。接触密集任务的接触点常被夹爪遮挡、常是透明/反光/细长物体，恰好是误差最大的地方。DRA 的目标不是把整张深度图算到最准，而是**在需要判断的那一小块 ROI 上，给出可信/不可信的明确标记**。

### 2.2 定义

对头部校正双目，先转 luma（数据是 AV1 `yuv420p`，色度 4:2:0；JPEG 虽 4:4:4，但源头色度已降采样），在 ROI 上做 SGM/半全局匹配，得到 `D̂` 与匹配代价 `C`。逐像素不确定度：

`σ_D² = (∂D/∂δ)² σ_δ² + σ_geo² + σ_calib²`

`∂D/∂δ = −D²/(fB)`；`σ_δ` 由匹配代价曲率、左右一致性、时序残差合成；`σ_geo` 覆盖飞点/遮挡边界；`σ_calib` 覆盖标定漂移。可靠性

`r(u,v) = P(|D̂−D| ≤ τ | evidence)`

用 GSO-D 的深度 GT + 少量真机锚点做 isotonic/保形校准。输出 `(D̂, σ_D, r)`，以及 `T_α={r≥1−α}`。

### 2.3 关键工程约束

- **只算 ROI**：接触区、目标物体、夹爪附近；避免全图 SGM 的延迟。
- **关键帧触发**：不是每步都算；在子目标切换、`unknown`、`regressed` 候选时算。
- **降采样有代价**：`image_resize` 若只改单目或左右不一致，会破坏标定；若左右同比例缩放，需同步缩放 `f` 与 `cx`，基线不变，`Z` 不变；但视差也同比缩小，亚像素误差的相对影响变大。
- **延迟目标**：ROI 160×120、关键帧触发时，SGM + 一致性检查 + 校准目标 < 20 ms；不达标则降 ROI 或隔帧。

### 2.4 伪代码

```python
def depth_reliability(obs, K, B, roi, tau, k=2.0):
    L = luma(obs["observation.images.cam_left_high"])
    R = luma(obs["observation.images.cam_right_high"])
    Lr, Rr = crop(L, roi), crop(R, roi)

    D, cost = sgm(Lr, Rr, K, B)                 # 米制深度
    lr      = left_right_consistency(Lr, Rr, D)
    tex     = texture_energy(Lr)
    spec    = specular_mask(Lr) | transparent_mask(Lr)
    temp    = temporal_residual(D, prev_D)

    sigma = propagate(D, cost, lr, tex, spec, temp, K, B)
    r     = calibrate_reliability(sigma, D, tau)   # GSO-D + 真机锚点
    return D, sigma, r
```

def tri_predicate(op, D, sigma, k=2.0):
    lo, hi = D - k * sigma, D + k * sigma
    if op.is_lt(hi):  return "true"
    if op.is_gt(lo):  return "false"

def verify(obs, g):
    D, sig, r = depth_reliability(obs, K, B, contact_roi(obs), tau_g)
    T = r >= 1 - alpha_g

    if all_true(support(g), D, sig, T, k) and cvh.ok_done(g, obs):
        return "done"
    if any_false(support(g), D, sig, T, k) \
       and temporal_change(D, prev_D, sig) > k \
       and cvh.ok_regressed(g, obs):

    return "unknown"

## 3. UIP-17 · KMV（Kinematic Multi-View）

### 3.1 直觉

腕部单目没有第二视角，但机器人可以自己制造视角。只要末端位姿已知，腕部相机在不同时刻就是一台「运动双目」；基线由运动产生，视差由运动产生。接触点离腕部近（0.2–0.5 m），只需几厘米的有效基线，就能把深度误差压到毫米级。

### 3.2 定义与误差

对同一特征点在时刻 `i,j` 的观测，三角化 `X`。有效基线

`b_eff = ||(I−ẑẑᵀ)(t_i−t_j)||`

视差角 `θ≈b_eff/Z`，深度不确定度

`σ_Z ≈ Z²/(f·b_eff)·σ_px`

可靠性 `r_kmv = 1[θ≥θ_min]·1[reproj≤ε]·exp(−κ/κ₀)`。示例：腕部 `f≈436 px`，`Z=0.4 m`，横向移动 4 cm，`σ_px=0.5 px` ⇒ `σ_Z≈4.6 mm`；移动 8 cm ⇒ `≈2.3 mm`。代价是运动时间与扰动风险。

### 3.3 与开环 chunk 的冲突

评测端整块执行后才重新调用 `get_action`，所以「主动看」只能在 chunk 边界发生。KMV 必须把「小幅移动 → 多视角采集 → 回到任务」编排成一个**感知 chunk**（小 `k`），而不是每步都动。UIP-13 的 ACS 负责给感知 chunk 分配小 `k` 与时间预算。

### 3.4 伪代码

```python
def kmv_depth(obs_hist, fk, K_w, theta_min=0.05, eps=1.5):
    poses  = [fk(o["observation.state.left_arm"]) for o in obs_hist]
    tracks = track_features([o["observation.images.cam_left_wrist"] for o in obs_hist])

    X, reproj, kappa = triangulate(tracks, poses, K_w)
    b_eff = effective_baseline(poses, X)
    theta = b_eff / max(X.z, 1e-3)

    r = (theta >= theta_min) and (reproj <= eps)
    return X, r, kappa, theta
```

### 3.5 安全包络

- 最大横向位移（如 5–8 cm）、最大速度、最大加速度；
- 用头部双目/本体感觉做碰撞预检；
- 只对「接触点/目标物体」做 KMV，不对整场景做；
- 失败则退回头部双目或单目相对深度，绝不卡死。

## 4. UIP-18 · CVH（Conformal Verification Head）

### 4.1 直觉

模型说「0.93 的概率 done」不等于「宣告 done 的误判率 ≤ 7%」。在透明/反光/分布外场景，softmax 会系统性过自信。保形风险控制给的是**有限样本、分布无关**的上界，正好匹配「步骤分不能被假推进吃掉」的需求。

### 4.2 定义

标定集 `{(o_i,y_i)}`，`y∈{done,not_done}`。定义单调损失

`ℓ_λ(o,y) = 1{score_λ(o) ≥ λ 且 y=not_done}`

选择 `λ̂` 使 `(1/n)Σℓ_λ̂ ≤ α`（带 `(n+1)` 修正）。测试期在可交换性假设下 `E[ℓ]≤α`。对 `regressed` 使用更保守的 `α_reg < α_done`，因为「误判撤回→反复重做」的代价不对称。

### 4.3 数据与偏移

- 标定数据优先来自真实/高保真回放；GSO-D 只做预标定；
- sim-to-real 偏移用 weighted conformal 或真机锚点重标定；
- 每类任务单独标定，避免跨任务混合导致阈值失真；
- 若无法满足可交换性，明确降级为「经验风险控制」，并在报告中标注。

### 4.4 伪代码

```python
def fit_threshold(scores_neg, alpha):
    n = len(scores_neg)
    q = min(1.0, ceil((n + 1) * (1 - alpha)) / n)
    return quantile(scores_neg, q)

def ok_done(g, obs):
    return cvh_score(g, obs) >= lambda_done[g.task]

def ok_regressed(g, obs):
    return cvh_score_reg(g, obs) >= lambda_reg[g.task]
```

## 5. UIP-19 · RBG（Reliability-Budgeted Governor）与 UIP-20 · SIW（Sensor Integrity Watchdog）

### 5.1 RBG：不是越谨慎越好

设子目标 `g` 的分值 `v_g`，下游价值

`V_g = v_g + Σ_{h>g} v_h·P(reach h | g correct)`

风险预算

`α_g = α_total·(1/V_g) / Σ_h(1/V_h)`

补测决策用 VOI：

`acquire if E[Δscore|acquire] > λ_t·E[Δt]`

并受三个硬约束：`time_left ≥ min_time_to_finish`、`P(τ>L_max)≤δ`、`max_redo`。当预算耗尽或时间不足时，**强制推进到下一个可拿分的子目标**，避免「为了完美验证而零分」。

### 5.2 SIW：传感器也会犯错

检查项：

- 形状/ dtype / 时间戳单调性；
- 模糊（Laplacian 方差）、JPEG 块效应、过曝/欠曝；
- 立体极线残差、左右一致性覆盖率；
- 标定漂移：用已知夹爪几何/末端位姿在图像中的重投影残差做在线自检；
- 帧间时间差与 `obs_delta_indices` 是否一致。

失效动作分级：`hold`（保持安全姿态）→ `reduce_k`（缩短块长）→ `fallback_mono`（退回单目/本体感觉）→ `safe_stop`。**绝不因为传感器异常而返回形状/统计异常的动作**，否则会伤可信度。

### 5.3 伪代码

```python
class RBG:
    def should_acquire(self, g, r, time_left):
        V = self.downstream_value(g)
        p_unknown = fraction(r < 1 - self.alpha[g])
        gain = V * p_unknown
        cost = self.lambda_t * self.expected_acquire_time(g)
        return gain > cost and time_left > self.min_time_to_finish(g)

    def k_for(self, g):
        if self.phase[g] in ("contact", "verify", "redo"):
            return self.k_small
        return self.k_max
```

## 6. UIP-11′ · GSO-D 与 UIP-12′ · DRF-D

### 6.1 GSO-D：带深度 GT 的计分神谕

- 在 Gazebo 中为 3–5 个代表任务建场景（T26 插网线、T27 叠碗、T19 拉链、T16 叠毛巾、T23 球拍）；
- 渲染 RGB + 深度 GT，用几何谓词精确判每个计分步（接触、插入深度、堆叠关系、覆盖面积）；
- 用真机/公开数据拟合深度噪声模型：`σ(Z, material, texture, motion)`，再注入仿真 rollout；
- 用途：① 校准 `r`；② 拟合保形阈值；③ 做消融与回归测试；
- **边界**：Gazebo 的透明/反光渲染不物理，不能当像素级真值；只做「结构/顺序/可靠性校准」，最终以真机锚点为准。

### 6.2 DRF-D：深度失效数据工厂

- 在 v2 的「反向撤回」脚本上，叠加深度失效：
  - 距离相关高斯噪声 `σ∝Z²`；
  - 飞点/遮挡边界、镜面空洞、透明体缺失；
  - 运动模糊、JPEG/AV1 压缩、帧丢失、左右目不同步；
  - 基线/标定小扰动。
- 训练可靠性头的**自监督信号**：左右一致性、时序光度一致、KMV 重投影一致；少量 GT 只用于校准。
- 课程：干净 → 轻度 → 重度；先学「何时 unknown」，再学「如何在 unknown 下行动」。

## 8. 合规与风险（本轮新增重点）

- **单模型合规**：优先经典 SGM + 共享骨干上的小型可靠性头；不引入外部大模型。保形校准是离线后处理，不构成推理期第二模型。若用学习式立体/深度头，必须与主骨干同属一个模型。
- **不要请求未知键**：接口目录没有 depth；`obs_delta_indices` 只能声明目录内键，否则会被拒。
- **缩放不能破坏标定**：若 `image_resize` 左右不一致，或只缩一路，深度会错；左右需同比例缩放并同步更新 `K`。
- **色度陷阱**：数据源头 AV1 `yuv420p`，匹配优先用 luma；不要依赖色度边缘做亚像素。
- **标定漂移**：公开 `camera_params` 只是先验；真机可能有安装误差。用 SIW 的在线重投影自检，不要让深度悄悄偏。
- **仿真过拟合**：GSO-D 的深度 GT 只用于结构与校准，不能替代真机；透明/反光场景尤其要真机锚点。
- **保守瘫痪**：可靠性门控必须配 RBG 的强制推进兜底；否则会在时限内零分。
- **手册仍未取到**：5 轴中的位置/干扰物/背景、评测轮次/时限/控制频率仍待飞书手册公开后核实。

## 10. 本轮最大风险 & 押注

**一句话**：若把「可靠性」做成一个永远不敢确认的高阈值，系统会在时限内瘫痪；必须用风险预算把「补测」与「强制推进」统一成一个可计算的决策。

**→ 押注：UIP-01″（可靠性门控验证）× UIP-16 DRA × UIP-17 KMV × UIP-18 CVH 组成的「可自检深度感知闭环」**——它补上 v2 缺失的前提（验证器凭什么相信眼睛），同时保留 v2 的得分靶点（人为反向撤回），并且完全落在选手 API 权限与离线算力之内。**最大的风险是：仿真深度 GT 与真机深度失效模式不一致，导致可靠性图在真机上过度自信或过度保守。**
