# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配交互消歧闭环」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「演示数据」×「目标检测」）

> R69 让系统学会了「问」，却默认了两件从未被验证的事：**(a) 动作模态的语义只在演示数据的支撑集内成立**；**(b) 我要操作的那个「对象」是被正确感知、且就是演示里那个对象**。R69 的全部效率收益——模态分解、VoI 交互、resolution bonus——都建立在这两条默认之上。可现实中的任务是「对某个对象做某个动作」：**演示数据给出「做什么」，目标检测给出「是哪个」**。一旦「是哪个」错了，策略会以极低的 U_ale/U_epi、极高的置信度，对**错误的对象**做**正确的动作**。这比 R69 自陈的风险更隐蔽：不是「追问一个幻影」，而是**认错对象还浑然不觉**。
>
> 本轮两个灵感正好补上这块地基：
> - **演示数据**把「策略可信域」从一句口号变成一个可检索、可版本化、可审计、也可被投毒的数据支撑集；
> - **目标检测**提供从演示语言落到像素的**地址总线**：对象身份、外观嵌入、关系结构、检测置信度。
>
> 核心命题：在 R69 的 (U_ale, U_epi) 之外引入第三条正交接线 **U_ref（指称不确定性）**，并交付一个「演示支撑测试 + 对象指称认证」的门：**只有当前场景落在演示支撑集内、且对象指称被认证，R69 的交互消歧才被允许；否则禁止交互（因为问也是在错误的前提下问），退化为 R68 的保守，或直接安全停机。** 命名 **TETHER-RAS**（Teach-data Envelope Test with Honest Evidence Referencing）：把每一条演示牢牢「拴」在它真正描述的那个对象上；地址一断，动作即刻降级。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**我面对的，还是演示里的那个东西吗**」——安全不只是把刹车踩对，还要确认**这脚刹车是为眼前这辆车踩的**。

## 0. 直觉与动机

**灵感 1（演示数据 → 策略的语义边界就是演示支撑集）**
直觉：行为克隆从不在全状态空间上正确，它只在一个由演示覆盖的流形附近有语义。R69 的流匹配模态分布同样是从演示里学出来的：演示没覆盖的分叉，采样出的「模态」只是外推的幻觉。于是 U_epi 的「可约性」有一个从未言明的前提——**歧义必须落在演示支撑集内**。支撑集内的歧义是「还没问」；支撑集外的歧义是「问了也不知道该拿什么先验去理解答案」。演示数据因此不只是训练集，而是**策略的语义有效期**：它规定了「我凭什么相信我知道自己在干什么」。

**灵感 2（目标检测 → 把演示落到像素上的地址总线）**
直觉：演示片段天然是对象中心的——「抓红色杯子」「绕开椅子」「把盖子拧上」。目标检测把场景解析成对象节点（框、类别、外观嵌入、置信度）与关系边（相对位姿、接触、包含、可供性）。演示与当前场景的对应，本质是一次**对象级图匹配**：演示里的「红色杯子」，对应当前哪一个检测框？这个匹配一旦错位，策略再准也只是「对错对象做对动作」。检测不是感知的细节，而是**任务语言与物理世界之间的地址翻译器**：地址译错，指令越精确越危险。

**灵感 3（第三通道 → R68/R69 都缺「我指的是谁」）**
直觉：R68 的残差通道测「传感器自洽」，R69 的似然通道测「行为自洽」，两者都**以对象身份正确为前提**。而对象身份错误恰恰能让两条通道都显得正常：传感器没坏（像素是真的），动作对某个对象也很合理（只是不是那个对象）。于是需要第三条正交通道：**对象指称通道**——检测跨帧/跨视角的一致性、演示对象与当前对象的对应证据、动作与对象可供性的语义冲突。三者构成「传感器 / 行为 / 指称」的正交证据三角，也正好补上 R69 定义 293-iii 里只说了「k 个正交源」却没点名的空缺。

**灵感 4（演示是持久数据 → 与 R69 的一次性回答本质不同）**
直觉：R69 的交互回答是**一次性、临时**的：问完只用于当轮后验，不改变任何参数。演示数据是**持久、可累积、会改变未来行为**的。如果允许「问不到答案就去要一段演示」，就必须回答数据供应链问题：谁给的、在什么标定/检测器版本下给的、经过什么验证、会不会是投毒。**实时零学习写操作这一不变式不能破**：演示请求只能进**隔离教学队列**，离线认证与回放通过后才可追加到演示库。R70 因此把「交互」正式分成两类：**要答案（在线、临时）** 与 **要演示（离线、持久）**——这是本轮在系统架构上最硬的一条切分。

**灵感 5（演示是双刃剑 → 持久谎言比临时谎言更可怕）**
直觉：R69 担心的是一次被误导的回答；R70 要担心的是**一条被投毒的演示**——它会被反复检索、反复复用，还盖上「已认证」的章。更隐蔽的是，攻击者不必改演示本身，只需用对抗补丁骗过检测器，让当前场景「看起来像」某个演示对象，从而让系统主动把错误演示**取出来用**。所以本轮不能只讲收益，必须同时交付：演示来源与版本钉扎、检测器校准门、图关系约束的组合防御、教学队列的隔离与红队回放。否则 TETHER 只是给 R69 装了一个更自信的「认错人」模块。

## 1. 形式化定义（增量：定义 310–326）

**定义 310（TETHER-RAS 总览）** TETHER-RAS = (OCT, DSA, CORR, DG, RAC, TQ, RAS-WM‡)。三不变式：
(i) **实时零学习写操作**（继承 R68 定义 276-i）：演示请求不得在实时环内改变任何参数或演示库；
(ii) **演示库只追加且隔离**：任何进入演示库的原子必须带来源签名、检测/标定版本钉扎、离线回放与红队通过记录；
(iii) **指称纪律**：未通过对象指称认证或不在演示支撑集内时，不得执行 R69 的交互消歧，也不得按演示模态执行，只能保守退化或安全停机。

**定义 311（对象中心场景图 OCT）** 检测器给出 G_t = (V_t, E_t)。节点 v_i = (b_i ∈ ℝ⁴, c_i, e_i ∈ ℝ^{d_e}, q_i ∈ [0,1])（框、类别、外观嵌入、检测置信度）；边 e_{ij} 编码空间关系（相对位姿、接触、包含）与可供性关系。G_t 是演示与当前场景共享的**地址空间**；定义 325 要求策略条件编码使用同一地址空间或显式对齐投影。

**定义 312（演示原子）** 演示原子 d = (G_d, ξ_d, ρ_d)，其中 G_d 是演示时的对象场景图，ξ_d 是动作块，ρ_d = (teacher_id, t, detector_ver, calibration_ver, hash) 是来源指纹。演示库 𝒟 = {d} 只追加、不可原地修改。

**定义 313（对象指称认证 CORR）** 匹配 M: V_d ⇀ V_t 为部分单射，最大化 Σ sim(e_i, e_j) − λ_c·[c_i ≠ c_j]，约束：任务相关节点必须被匹配、类别一致、关系边在阈值内保持。认证通过 ⟺ M 存在 ∧ 每个匹配节点 q_j ≥ τ_q ∧ 关键关系保真度 ≥ τ_rel。输出指称证书 ref_cert = (M, margin, relation_score, detector_ver)。

**定义 314（演示支撑测试 DSA）** 检索 top-k 演示原子 {d}，定义支撑分 S(o_t) = max_d W(G_t, G_d)，W 为基于最优传输/图匹配的场景距离。用共形预测给出「在支撑内」的 p 值：p(o_t) = (1 + #{d_cal : S(o_t) < S(d_cal)}) / (n+1)。**in-support ⟺ p ≤ α_sup 且 ref_cert 通过**。α_sup 控制「支撑外被误判为支撑内」的比例；它是有统计含义的，不是安全证明（见引理 20）。

**定义 315（指称不确定性 U_ref）** U_ref = 1 − P(指称正确 | 观测)，由匹配 margin、检测器校准置信、跨帧/跨视角一致性三者融合。与 U_ale、U_epi **语义正交**：U_ale/U_epi 是「同一个对象上动作怎么选」，U_ref 是「这个对象是不是那个对象」。三者不做简单加和，分别进入不同门（定义 324）。

**定义 316（版本钉扎与陈旧失效 DPB）** 每个原子 ρ_d 钉扎 detector_ver 与 calibration_ver。当前检测器版本与钉扎不一致时，G_d 的对象标签/外观统计可能已迁移 ⇒ 原子进入 **stale** 状态：只能以降低的检索权重参与，或触发重索引；关键任务原子 stale 时不得单独支撑执行。

**定义 317（支撑条件化模态集）** 流匹配策略的模态 {m_k} 改为以检索到的演示原子为条件：π_θ(ξ | o_t, d)。**支撑集外不得解释模态**——此时 mode_head 的输出不具语义，R69 的分辨/追问一律禁用（因为「先验地址」错了，追问只是在错误的坐标系里提问题）。

**定义 318（交互二分：要答案 vs 要演示）** 在线 MINT 只允许**要答案**（临时，落入当轮后验，不改变参数）。**要演示** 是持久请求：生成一个带状态键的 demo_request，进入教学队列；其效果只能在离线认证并追加后，于**下一轮及以后**生效。

**定义 319（演示门 DG）** 决策四分：① in-support ∧ ref_cert ⇒ 允许 R69 消歧后执行；② in-support ∧ ¬ref_cert ⇒ 不执行，加重保守并尝试低成本澄清指称（重新观测，不改变参数）；③ ¬in-support ∧ 指称可认证 ⇒ 不按演示执行，退 R68 保守，并把状态键入教学队列；④ ¬in-support ∧ ¬ref_cert ⇒ 安全停机/请求人类接管。任何情形都不允许「无支撑 + 无指称」仍按模态执行。

**定义 320（指称异常通道 RAC）** 三条独立证据：(a) 检测跨帧/跨视角一致性（身份持续性、框抖动、类别翻转）；(b) 演示对象与当前对象的外观/关系失配；(c) 策略动作与演示对象语义的可用性冲突（如对「杯子」执行「拧盖子」）。RAC 输出与 R68 残差、R69 似然并列的第三异常分 a_ref。

**定义 321（演示威胁模型 ℰ_demo）** 演示标签投毒、触发器后门、针对检测器的对抗补丁、演示选择投毒（专门污染长尾类）、陈旧检测器下的错误标签迁移。并入 AIC：ℰ_TETHER = ℰ_FLUID × ℰ_demo × ℰ_ref（指称错配）。

**定义 322（三源证据纪律）** 证据源 ℰ = {r_res（传感器）, a_score（行为似然）, a_ref（对象指称）}。定案需**至少两源一致（2-of-3）**；指称源与行为源不得由同一编码器产生（防相关失效）。R69 的「k 个正交源」由此被具体化。

**定义 323（证书 J_TETHER）** J_TETHER = (J_FLUID, support_p, ref_cert_hash, provenance_hash, detector_ver, U_ref, stale_flag, teach_queue_hash)。Valid ⇔ Valid(J_FLUID) ∧ (in-support ∨ 明确拒绝执行) ∧ 指称纪律满足 ∧ 演示库版本一致。

**定义 324（四级退避与支撑红利）** ① in-support ∧ ref_cert：可用 R69 resolution bonus，λ = λ_floor(U_ale)（仅在 U_epi 消解后）；② in-support ∧ ¬ref_cert：λ = λ_floor(U_ale + U_epi + U_ref)；③ ¬in-support：禁用交互，λ = λ_floor(U_ale + U_epi + U_ref)，按 R68 最保守；④ 指称不可认证且风险高：安全停机。**R69 是「支撑恒成立且指称恒认证」的边界情形**。

**定义 325（共享地址约束）** 演示检索、支撑测试、策略条件编码必须使用**同一套对象中心表征**（或显式对齐的投影），否则会出现「检测说 A、策略以为 B」的隐性错配。这是工程不变式，也是可审计性的前提：两套对象概念之间的缝隙，正是 R70 最可能漏掉故障的地方。

**定义 326（教学队列协议 TQ）** demo_request 经：隔离 → 人类示教/自动采集 → 检测器自动标注 + 一致性检查 → WM 回放验证 → 红队（投毒/补丁）→ 人工签署 → 追加。任何一步失败即丢弃；队列操作**全部离线**，实时环只读。

# IP-264 OCT：对象中心场景图（复用 R68/R69 感知，避免重复检测）
def build_scene(o_t, detector):
    dets = detector(o_t)                       # 框 / 类别 / 嵌入 / 置信
    return SceneGraph(nodes=dets, edges=relation_edges(dets))

# IP-266 CORR：对象指称认证（类别约束 + 外观 + 关系保真）
def certify_reference(G_d, G_t, tau_q, tau_rel):
    M, margin = graph_match(G_d, G_t)          # 部分单射，任务节点必须匹配
    ok  = all(G_t.q[j] >= tau_q for j in M.values())
    ok &= relation_fidelity(G_d, G_t, M) >= tau_rel
    return RefCert(M, margin, ok, detector.ver)

# IP-265 DSA：演示支撑测试（检索 + 共形 p 值）
def demo_support(G_t, demo_store, calib_scores, alpha_sup):
    ds = demo_store.retrieve(G_t, topk=8)      # 对象中心嵌入 ANN
    S  = max(scene_distance(G_t, d.G) for d in ds) if ds else float('inf')
    p  = (1 + sum(S < s for s in calib_scores)) / (len(calib_scores) + 1)
    return p, ds, (p <= alpha_sup)

# IP-267 DG：演示门（四分决策，安全侧单调）
def demo_gate(p, ref_cert, stale, risk):
    if p <= alpha_sup and ref_cert.ok and not stale:
        return 'R69_DISAMBIGUATE'              # ① 允许 R69 交互
    if p <= alpha_sup and not ref_cert.ok:
        return 'REOBSERVE_SLOW'                # ② 只澄清指称，不改参数
    if p > alpha_sup and ref_cert.ok:
        return 'REQUEST_DEMO'                  # ③ 入离线队列，本轮保守
    return 'SAFE_STOP'                         # ④ 无支撑 + 无指称

# IP-268 RAC：指称异常通道（第三意见）
def ref_anomaly(G_hist, G_d, ref_cert, action, G_t):
    a_persist = identity_consistency(G_hist)             # 跨帧/跨视角
    a_match   = appearance_relation_mismatch(G_d, ref_cert)
    a_afford  = affordance_conflict(action, G_t)
    return fuse(a_persist, a_match, a_afford)

# IP-275 主闭环（继承 R69，仅在入口加指称门）
def TETHER_RAS_round(M, obs):
    z, o = M.mtm.forward(obs)                  # R69 一次前向
    c, U_cal, thr = M.cof.step(...)            # R68 标定
    G_t = M.oct.build(o)
    p, ds, in_sup = M.dsa.test(G_t, M.demo_store, M.calib_scores, M.alpha_sup)
    ref  = M.corr.certify(ds[0].G, G_t) if ds else None
    stale = M.dpb.is_stale(ds[0]) if ds else True
    gate = M.dg.decide(p, ref, stale, M.risk)
    a_ref = M.rac.score(M.G_hist, ds[0].G if ds else None, ref, M.last_action, G_t)
    if gate == 'R69_DISAMBIGUATE':
        k, lam, mode, U = M.fluid_round(o, G_t, cond_d=ds[0])   # 模态以 d 条件化
    elif gate == 'REOBSERVE_SLOW':
        k, lam, mode = M.retreat_observe(U_cal, a_ref)          # 只求指称澄清
    elif gate == 'REQUEST_DEMO':
        M.tq.enqueue(state_key(o), priority=M.risk)             # 离线队列
        k, lam, mode = M.r68_retreat(o, U_cal)                  # 本轮退 R68
    else:
        k, lam, mode = M.safe_stop(o)
    M.vqa_r.submit_async(gate, p, ref, a_ref)                  # 参与式审计
    return k, lam, mode, (in_sup, ref, a_ref)

## 3. 推导

**引理 19（指称正交性）** 存在策略在 (U_ale, U_epi) 任意小（高置信、单峰、动作似然高）时，指称错误概率 U_ref 仍可任意接近 1。构造：同一策略对任意同类对象给出相同动作分布；把对象 A 的观测替换为（经遮挡/对抗补丁后）仍被检测为 B 的观测，则 U_ale、U_epi 与 R69 的 a_score 均可保持不变，而指称已错。故 U_ref 不可由前两者推出，必须独立通道。**系：** R69 的「k 源一致」若不点名指称源，三源可能共享同一个错误前提——都以「对象身份正确」为隐含公理。

**引理 20（共形支撑有效性及其在漂移下的失效）** 在演示校准集与部署观测可交换时，in-support 误判率 ≤ α_sup（标准共形覆盖保证）。但在演示-部署分布漂移、检测器版本更新或对抗补丁下可交换性被破坏，经验覆盖率可任意偏离名义值 ⇒ 必须用加权共形/在线重标定，并以 DPB 版本钉扎检测「检测器变了」这一最容易被忽视的漂移源。**系：** 支撑测试是一个统计假设检验，不是安全证明；它只能降低风险，不能承诺零漏检。

**引理 21（演示投毒与图关系组合防御）** 设针对检测器的对抗补丁使单节点误检概率为 δ_det。要伪造一次通过认证的指称，需同时伪造类别、外观以及任务相关的关系边；在关系约束下，错误匹配被接受概率 ≤ δ_det^{k}·ρ_rel（k 为任务关键节点数，ρ_rel 为关系巧合率）。**系：** **对象图的关系结构比单对象检测更难伪造**——防御预算应优先投给「对哪些对象/关系做认证」，而不是无差别提升所有检测精度。

**定理 18（TETHER 严格包含 FLUID 与 R68）** 在定义 319–324 下，TETHER 在任意状态上的期望风险 ≤ FLUID ≤ R68；当 p ≤ α_sup、ref_cert 通过、非 stale 时，TETHER 与 FLUID **逐指令相同**（直接走 R69 路径），故效率上的 resolution bonus 完整保留；当上述任一不成立时，TETHER 只可能更保守（重观测/退 R68/停机），故安全侧单调不劣。R69 恰是「支撑恒成立 + 指称恒认证」的边界情形，R68 是其再退化边界。

**定理 19（零在线写、支撑单调增长与教学队列安全）** 教学队列只在离线改变演示库，实时环仅读 ⇒ 零学习写不变式继承。演示库只追加 + 认证门槛使支撑集单调不减，且每次扩张都有来源签名、版本钉扎与回放记录；一条坏演示最多使支撑集「暂时不扩张」，不会使已认证的安全行为退化（除非经显式、受审计的版本回滚）。**系：** 「要演示」不能成为在线越权的后门——它只改变未来，不改变当下安全包络。

## 6. 本轮最大风险

**一句话**：TETHER-RAS 把「认对对象」的最终判断交给了**检测器与演示标签**，而支撑门又让系统相信「我在支撑内」而**更不愿去问**——于是**一个被投毒或陈旧的检测器可以「认证」一次错误指称**，系统便以 R69 获得的全部自信，对错误对象执行正确动作；这正是「**对错对象做对动作**」，比 R69 的「问一个幻影」更难发现，因为它看起来一切自洽。

**次级风险与缓解**：
1. **检测器陈旧/漂移使演示地址过期** → DPB 版本钉扎 + stale 失效 + E308；
2. **共形支撑在分布漂移下失效** → 加权共形/在线重标定 + 引理 20 的显式假设声明；
3. **严格支撑门造成长尾过度停机（可用性风险）** → 分级退避而非一刀切 + E309 的停机率上界 + 教学队列补支撑；
4. **演示库成为持久投毒面** → 隔离队列 + 回放 + 红队 + 关系约束组合防御 + E306；
5. **两套对象概念隐性错配** → 定义 325 共享地址约束 + E315 消融，把「检测说的」与「策略以为的」强行对齐并审计。

# IP-264 OCT：对象中心场景图（复用感知，避免重复检测）
def build_scene(o_t, detector):
    dets = detector(o_t)                        # 框 / 类别 / 嵌入 / 置信
    return SceneGraph(nodes=dets, edges=relation_edges(dets))

# IP-266 CORR：对象指称认证
def certify_reference(G_d, G_t, tau_q, tau_rel):
    M, margin = graph_match(G_d, G_t)           # 部分单射，任务节点必配
    ok  = all(G_t.q[j] >= tau_q for j in M.values())
    ok &= relation_fidelity(G_d, G_t, M) >= tau_rel
    return RefCert(M, margin, ok, detector.ver)

# IP-265 DSA：演示支撑测试（检索 + 共形 p 值）
def demo_support(G_t, demo_store, calib_scores, alpha_sup):
    ds = demo_store.retrieve(G_t, topk=8)       # 对象中心嵌入 ANN
    S  = max(scene_distance(G_t, d.G) for d in ds) if ds else float('inf')
    p  = (1 + sum(S < s for s in calib_scores)) / (len(calib_scores) + 1)
    return p, ds, (p <= alpha_sup)

# IP-267 DG：演示门（四分，安全单调）
def demo_gate(p, ref_cert, stale, risk):
    if p <= alpha_sup and ref_cert.ok and not stale: return 'R69_DISAMBIGUATE'
    if p <= alpha_sup and not ref_cert.ok:           return 'REOBSERVE_SLOW'
    if p >  alpha_sup and ref_cert.ok:               return 'REQUEST_DEMO'
    return 'SAFE_STOP'

# IP-268 RAC：指称异常通道（第三意见）
def ref_anomaly(G_hist, G_d, ref_cert, action, G_t):
    return fuse(identity_consistency(G_hist),
                appearance_relation_mismatch(G_d, ref_cert),
                affordance_conflict(action, G_t))

# IP-275 主闭环（继承 R69，仅在入口加指称门）
def TETHER_RAS_round(M, obs):
    z, o = M.mtm.forward(obs); c, U_cal, _ = M.cof.step(...)      # R68/R69
    G_t = M.oct.build(o)
    p, ds, in_sup = M.dsa.test(G_t, M.demo_store, M.calib_scores, M.alpha_sup)

    if   gate == 'R69_DISAMBIGUATE': k, lam, mode, U = M.fluid_round(o, G_t, ds[0])
    elif gate == 'REOBSERVE_SLOW':   k, lam, mode = M.retreat_observe(U_cal, a_ref)

        k, lam, mode = M.r68_retreat(o, U_cal)
    else:                            k, lam, mode = M.safe_stop(o)
    M.vqa_r.submit_async(gate, p, ref, a_ref)
    return k, lam, mode, (in_sup, ref, a_ref)

## 4. 推导

**引理 19（指称正交性）** 存在策略使 (U_ale, U_epi) 与 `a_score` 任意小（高置信、单峰、似然高）而 `U_ref→1`：同一策略对同类对象给相同动作分布，把对象 A 的观测换成被误检为 B 的观测即可。故 U_ref 不能由前两者推出，必须是独立通道。系：R69 的 k 源一致若不点名指称源，三源可能共享「对象身份正确」这一错误公理。

**引理 20（共形支撑有效性与漂移失效）** 校准集与部署可交换时，in-support 误判率 ≤ α_sup；漂移、检测器版本更新或对抗补丁破坏可交换性后，经验覆盖率可任意偏离 ⇒ 需加权共形/在线重标定 + DPB 版本钉扎。系：支撑测试是统计检验，不是安全证明。

**引理 21（投毒与图关系组合防御）** 单节点误检概率 δ_det，要伪造通过认证的指称需同时伪造类别、外观与任务相关关系边 ⇒ 错误匹配接受率 ≤ `δ_det^k·ρ_rel`（k 任务关键节点数，ρ_rel 关系巧合率）。系：**关系结构比单对象更难伪造**，防御预算应优先给关键对象/关系。

**定理 18（TETHER 严格包含 FLUID 与 R68）** 任意状态期望风险 `≤ FLUID ≤ R68`；当 `p ≤ α_sup`、`ref_cert` 通过、非 stale 时与 FLUID 逐指令相同（保留 R69 resolution bonus）；否则只更保守（重观测/退 R68/停机）。R69 = 「支撑恒真 + 指称恒认证」边界，R68 为其再退化边界。

**定理 19（零在线写与支撑单调增长）** 教学队列仅离线改库，实时只读 ⇒ 零学习写继承；只追加 + 认证门槛使支撑集单调不减，每次扩张有来源签名、版本钉扎与回放记录；坏演示最多使支撑暂不扩张，不退化已认证的安全行为（除受审计的显式回滚）。系：「要演示」不能成为在线越权后门，只改变未来，不改变当下安全包络。

## 7. 本轮最大风险

**一句话**：TETHER-RAS 把「认对对象」的最终判断交给**检测器与演示标签**，而支撑门又让系统相信「我在支撑内」而**更不愿去问**——**一个被投毒或陈旧的检测器可以「认证」一次错误指称**，系统便带着 R69 的全部自信，对错误对象执行正确动作：这是「**对错对象做对动作**」，比 R69 的「问一个幻影」更难发现，因为它看起来处处自洽。

**次级风险与缓解**：检测器陈旧/漂移使演示地址过期（DPB 版本钉扎 + stale 失效 + E308）；共形支撑在漂移下失效（加权共形/在线重标定 + 显式假设声明）；严格支撑门导致长尾过度停机（分级退避 + E309 上界 + 教学队列补支撑）；演示库成持久投毒面（隔离队列 + 回放 + 红队 + 关系约束组合防御 + E306）；两套对象概念隐性错配（定义 325 共享地址 + E315 消融，把「检测说的」与「策略以为的」强行对齐并审计）。
