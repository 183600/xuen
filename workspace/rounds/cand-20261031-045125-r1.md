# 第 13 轮 · PACE：把「1 秒开环 chunk」改成「预算内闭环」，用动力学重定时和跟踪误差把远程 API 的延迟变成可控变量

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮承接第 12 轮 CHUNK-SERVO，不推倒它；三个灵感词是「通信延迟」「动力学」「对比实验」。本轮的核心变化是：**先把延迟和动力学当成一等公民来测量，再决定控制策略；不是再换一个更大的 VLA。**

## 0. 先给结论：上一轮有两个事实需要修正，修正后优先级变了

本轮重新抓取和读数据后，有三条会直接改变方案的硬事实：

1. **腕部相机不是「没有内参」。** 32/32 个 HF 数据集的 `camera_params.wrist_left/right.color.camera_matrix` 都存在，fx≈432.9–437.5、cx≈323.9、cy≈242.9，另有 ir1/ir2 和 `extrinsics_to_color`。第 12 轮「腕部无内参、必须一次性标定」的判断至少对当前数据版本是错的。**G0 的门槛降低，但手眼外参（腕相机→EE）仍然没有，仍需标定。**
2. **动作和状态之间存在约 2–3 帧（67–100ms）的时间错位。** 在 HangCup、PlugInEthernet、ZipUp 三个数据集的 file-000 样本上，`action(t)` 与 `state(t+k)` 的平均绝对误差在 k=3 时最小（左臂 0.0114–0.0127 rad；右臂 k=2–3）。这不是网络 RTT，而是数据/控制链路的固有延迟；部署时还要再叠加公网 RTT。**任何「动作时间对齐」都必须显式补偿这个偏移。**
3. **`action_chunk_size` 是 handshake 时固定的，不能在线改。** README 和 `ExampleEnv` 都把它当 metadata 常量；`get_action` 每次返回固定 leading time-axis。第 12 轮「按 RTT 动态改 chunk size」在协议上不成立。**在线自适应只能通过「动作内容」实现：软截断、保持、制动、进度对齐，而不是改 chunk 长度。**

这三条把本轮的重点从「再做一个视觉伺服」推到两个更底层的问题：

- **通信延迟**：延迟不只是 RTT，还包括观测上传（4 路图 × 时间堆叠 × JPEG q95 4:4:4）、推理、多端口共享 GPU 的排队。官方 `web_policy.py` 默认 JPEG quality=95、subsampling=0；如果按示例堆叠 4 帧，4 路就是 16 张图/请求。**观测带宽是比模型推理更隐蔽的延迟源。**
- **动力学**：在三个任务样本上，`state(t+30)` 与 `action(t)` 的平均偏差是 0.083–0.162 rad（约 4.8–9.3°），而闭合环（lag 3）只有 0.011–0.015 rad，差 5.5–13 倍。**30 步开环不是「有点不准」，而是把 1 秒后的状态交给运气。** 同时，快速段的跟踪误差是慢速段的 1.5–3.5 倍，说明动力学风险与速度/加速度强相关，适合做自适应重定时。

所以本轮的押注是 **PACE（Proprioceptive-Aware Chunk Execution）**：

> **用「观测带宽预算」把端到端反馈周期压进预算；用「AnyTime-Chunk + 进度对齐 + 软截断」在固定 chunk 协议内实现事件触发的有效 horizon；用「跟踪误差残差」在无 F/T、无深度的 API 上做接触/滑移/干扰检测；用「STEP 序贯实验 + sham 对照 + 延迟注入」证明每一分提升不是噪声。**

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **通信延迟** | 观测 payload 预算（相机路数/分辨率/堆叠帧数）；多端口共享 GPU 的 deadline 调度；AnyTime-Chunk 在预算内返回缓存 plan；软截断避免 evaluator 等待 | 不做 30Hz 广域网伺服；不假设 RTT 是常数；不把推理延迟当唯一延迟 |
| **动力学** | 用 G1 URDF 的关节限位/速度/力矩做可行性过滤；进度对齐从当前实际状态重新拼接；接触段用跟踪误差触发减速/软截断；用加速度/jerk 而非速度上限做风险指标 | 不做完整动力学辨识；不做力矩控制（API 没有）；不做第二个学习残差策略 |
| **对比实验** | 预注册 + STEP 序贯检验 + 配对/McNemar；sham servo/sham retime 阴性对照；延迟注入 0/50/100/150ms；方差分解；MDE 先算再跑 | 不用 5 次 A/B 下结论；不把预览榜单当难度表；不在正式 320 trials 上做探索 |

## 1. 榜单与头部方案：仍然只能当「预览」，不能当 SOTA

2026-10-31 复核：首页仍展示 8 个模型预览（MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%）；`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`；`runs.html` 从「即将发布」变成了 256 条记录（8 模型 ×32 任务），但 `details.html` 仍写着「测试视频占位，后续可替换为真实视频文件」；成功率仍出现 21.5%、29.3% 等非 10 次 trial 整数倍。**结论不变：榜单是预览/合成数据，不能反推真实失败分布。**

头部模型的公开路线也不变：MolmoAct2 是 action reasoning + 3D 空间推理；WALL-OSS-0.5 是 4B VLA；DreamZero 是 14B world-action；π0.5 是开放世界泛化 VLA；GigaBrain-0 用世界模型生成数据；GR00T N1.5 是通用人形 VLA。它们的共同瓶颈仍是「开环 chunk + 接触精度 + 远程延迟」，但本轮不再从榜单排名挖创新点，而是从**官方接口实现、数据时间结构和 G1 动力学**挖。

## 2. 创新点清单（P0/P1/P2，每点含动机、差异、可行性、资源、步骤、风险）

### P0-1 · OBB：观测带宽预算（Observation Bandwidth Budget）

- **动机**：官方 `web_policy.py` 对每帧做 JPEG q95、4:4:4；`obs_delta_indices` 允许对图像做时间堆叠（示例对状态用 `[-10,-5,-2,0]`）。若 4 路图各堆 4 帧，就是 16 张 480×640 JPEG/请求。用自然图像量级估算，q95 4:4:4 单帧 28KB（简单图）到 100–250KB（复杂桌面图）；16 帧就是 0.45–4MB。10Mbps 上行对应 0.36–3.2s，50Mbps 对应 0.07–0.64s。**这比 6B 模型的 100–300ms 推理更可能成为主延迟。**
- **与现有方案的差异**：RTC/A2C2/VLASH 优化的是推理/执行重叠，默认观测已经在本地；竞赛是「观测先上传、动作再下发」的远程同步协议。OBB 把「传什么、传多大、传几帧」当成可优化变量，而不是固定开销。
- **技术可行性**：`image_resize` 和 `obs_delta_indices` 都是选手可声明的 metadata；只需离线/单任务通道做帕累托扫描。无需改 evaluator。
- **所需资源**：单任务通道若干次；一个能测量 payload/延迟的代理服务；3 种配置（4×480p stack4、3×320p stack2、4×256p stack1）。
- **落地步骤**：①在本地代理记录每次请求的字节数、JPEG 解码时间、端到端耗时；②在单任务通道对 3 个接触任务跑 3 种配置；③画「成功率–p99 延迟–payload」帕累托；④选不降成功率 >2pp 且 payload 降 ≥50% 的配置；⑤正式提交前锁定。
- **风险**：降分辨率可能伤小物体/透明物；堆叠帧少可能伤动态；需要按任务族验证，不能全局拍脑袋。

### P0-2 · AnyTime-Chunk：预算内返回「可执行的最优动作」

- **动机**：官方 evaluator 同步调用 `get_action`，等待返回后才执行 chunk；`PolicyService` 也是同步处理。如果 VLA 推理 + 上传 + 下载超过一个 chunk 周期，机器人就停顿。RTC 用 inpainting 解决，但需要 diffusion/flow 模型；我们需要一个与模型无关的服务层方案。
- **与现有方案的差异**：RTC 在模型内部冻结/补全动作；A2C2 训练一个修正头；VLASH 改异步推理；AnyTime-Chunk 不改模型，只在 `get_action` 里设时间预算：**能等到新 plan 就用新 plan，等不到就用旧 plan + 进度对齐 + 软截断**。它把「延迟」变成「预算」，而不是「故障」。
- **技术可行性**：后台线程/进程跑 VLA；主线程在 deadline 前返回；动作始终是合法 shape。官方 `PolicyService` 允许在 `get_action` 内做任意计算，只要不超时。
- **所需资源**：1 个 GPU 推理服务 + 每端口一个 CPU 轻量进程；需要实现 plan cache、future、deadline。
- **落地步骤**：①给每个端口维护 `plan`、`plan_idx`、`plan_ts`；②`get_action` 设 `deadline = now + B`（B 由实测 chunk 周期和 RTT 决定）；③若 future 完成则替换 plan，否则用旧 plan；④用当前实际状态做进度对齐（见 P0-3）；⑤异常时返回保持/制动 chunk。
- **风险**：旧 plan 可能已经过时；必须用进度对齐和软截断限制伤害；deadline 太短会频繁用旧 plan，太长会停顿。

### P0-3 · Soft-Truncation + 进度对齐：固定 chunk 内的「有效 horizon」

- **动机**：chunk size 固定，不能在线改；但 evaluator 只负责按顺序执行动作，不检查动作语义。我们可以在 chunk 后半段写入「制动到保持位姿」的轨迹，让机器人实际提前停下，等效于缩短 horizon。同时，chunk 开始时用当前实际状态重新拼接剩余轨迹，吸收上一 chunk 的跟踪误差。
- **与现有方案的差异**：VLA-Corrector 做「检测偏差→丢弃剩余→重新规划」，但需要 evaluator 提前调用；RoboPace 做 contact-aware TOPP-RA 重定时，但假设可以改执行节奏；我们在固定 chunk、同步调用的协议内，用**动作内容**实现截断和重定时，不需要改接口。
- **技术可行性**：只依赖 `observation.state`（关节/EE）和上一 chunk 的计划；用五次多项式/最小 jerk 拼接；限幅到关节速度/加速度；完全确定性。
- **所需资源**：离线回放 + 单任务通道；G1 URDF；一个轨迹拼接/重定时库（可自己写）。
- **落地步骤**：①离线用 30 步开环漂移数据标定「安全 horizon」；②实现 `progress_align(q_actual, plan)`；③实现 `soft_truncate(plan, risk)`：高风险段用制动轨迹替换；④在 3 个接触任务上 A/B；⑤若成功率不降且 p99 降，再推广。
- **风险**：截断可能让任务没做完；只在高风险/接触段启用；保留 VLA 后半段作为回退；修正幅度限幅（每 chunk ≤1cm/0.05rad）。

### P0-4 · D-RETIME：动力学可行的轨迹重定时

- **动机**：G1 手臂关节速度上限 37 rad/s（腕 pitch/yaw 22 rad/s），力矩 25/5 N·m；数据中关节速度中位数只有 0.14–0.22 rad/s，但加速度中位数 21–46 rad/s²、p95 39–79 rad/s²，最大 185 rad/s²。**真正的风险不是速度上限，而是加速度/jerk 和接触时的跟踪误差。** VLA 输出的是几何路径，不保证动力学可行。
- **与现有方案的差异**：RoboPace 用 TOPP-RA 做接触感知重定时；我们做轻量版：关节限位/速度/加速度过滤 + 时间缩放 + 接触段减速，且以「远程固定 chunk + 跟踪误差触发」为约束。不是完整 TOPP，而是可解释、可回退的过滤器。
- **技术可行性**：G1 URDF 公开；数据里有 `action.left_arm` 和 `action.left_ee_pose_gripper_base` 可做离线验证；API 的 `joint`/`ee` 两种模式都支持。
- **所需资源**：URDF/运动学库（Pinocchio 或自写）；离线回放；单任务通道。
- **落地步骤**：①解析 G1 关节限位/速度/力矩；②对 VLA 动作做前向检查；③违反时用时间缩放 `s` 放慢（二分搜索）；④接触段按跟踪误差/视觉接近度降速；⑤报告违规率、成功率、耗时。
- **风险**：过度保守会拖慢长任务（Toolbox 37.6s 平均，180s 上限）；需要按任务设时间预算；重定时可能改变接触时机。

### P1-1 · T-CONTACT：用「指令–实际跟踪误差」做无 F/T 接触检测

- **动机**：API 没有力/触觉/深度；但每个控制周期都有上一条动作 `q_cmd(t)` 和新的实际状态 `q_actual(t+1)`。接触会改变跟踪误差的幅度/方向。CoPRE 在 G1 上用关节力矩做到了 82.2% 召回、5.5N 推力 90% 检出；我们没有力矩，但位置跟踪误差是同一物理链路的更低信噪比代理。
- **与现有方案的差异**：第 11 轮 GEO-RESIDUAL 用视觉残差；T-CONTACT 用本体感知残差，对遮挡/透明物体更稳；与视觉残差互补，可做「双通道证据」。CoPRE 需要力矩，我们只需要位置，适配挑战赛 API。
- **技术可行性**：API 的 `observation.state.left_arm/right_arm` 和上一条 `action.*` 都可得；离线数据可验证。先用**无学习参数的阈值/动量观测器**，避免被判定为第二个模型。
- **所需资源**：3 个任务的全量 parquet（已有样本）；离线分析；单任务通道。
- **落地步骤**：①按速度分箱，估计自由空间跟踪误差分布；②用 `r = q_actual(t+1) - q_cmd(t)` 的范数/方向做接触分数；③用视觉残差做弱标签，算 AUROC；④若 AUROC<0.8，砍掉线上触发，只做离线分析；⑤若通过，接软截断/减速。
- **风险**：信号弱、受摩擦/负载/速度影响；误报会导致过早减速；需要自适应阈值和多帧累积。

### P1-2 · MP-Serve：多端口共享 GPU 的 deadline 调度

- **动机**：手册说评测跨 N 台机器人，提交须暴露 N 个连续端口；如果每个端口独立加载 6B 模型，显存不够；共享一个 GPU 就会排队。Armory 已经证明「异构 chunk 消费率 + naive batching」会让机器人 starvation，并用 lookahead 调度提升 18% 吞吐。竞赛正是这个设定。
- **与现有方案的差异**：第 12 轮只说「共享 VLA server」，没有排队模型；MP-Serve 把每个端口的 chunk 剩余时间当 deadline，用 EDF/lookahead 批处理，并在即将 starvation 时返回软截断动作。
- **技术可行性**：每端口一个轻量 `PolicyService`，通过本地 IPC 把观测发给一个 GPU 进程；GPU 进程维护每端口动作队列镜像；调度器按 deadline 组 batch。
- **所需资源**：1 张 24–80GB GPU；多进程/队列；压测工具。
- **落地步骤**：①先做单端口基线；②做 2/4/8 端口并发压测，测 p99 和 starvation；③实现 EDF；④实现 lookahead（优先保护快耗尽端口的 chunk）；⑤在全量干跑中验证无端口串扰。
- **风险**：复杂度高；官方 evaluator 的并发模式未知；先用保守并发 + 降分辨率保证 p99。

### P2-1 · X-PROTO：预注册 + STEP + sham 对照

- **动机**：正式评测只有 10 次/任务，单任务 10 trials 的 95% CI 约 ±30pp；5 次 A/B 只能看方向，不能看显著性。STEP（RSS 2025）证明序贯检验可在保持统计功效的同时减少最多 32% trials；Bifrost（2026-10-02）也指出配对/McNemar 能显著降样本量。**竞赛策略的核心不是多跑，而是少跑且不 p-hack。**
- **与现有方案的差异**：第 12 轮的「5 次 A/B + bootstrap」升级为「预注册 + 序贯停止 + 阴性对照 + 方差分解 + MDE」。
- **技术可行性**：单任务通道不计分，适合做配对/重复；正式评测只做确认。
- **所需资源**：统计脚本（STEP/McNemar/bootstrap）；实验日志；预注册模板。
- **落地步骤**：①写预注册（假设、主要终点、因子、样本量、停止规则）；②先算 MDE；③用 STEP 做两两比较；④加 sham servo/sham retime/delay placebo；⑤报告效应量 + 95% CI，不报裸均值。
- **风险**：单任务通道可能不支持固定初始条件，无法真正配对；备选是分层/重复测量；需要邮件确认。

### 保留、升级、剪枝

**保留**：DG-KEYFRAME（演示检索相对目标）、视觉伺服（作为 T-CONTACT 的互补通道）、数字孪生只做标定/风洞、单模型合规、竞赛任务组合、官方 WLA 基座。

**升级**：
- 固定 5 步 → 固定 chunk + 软截断/进度对齐（协议不允许改 chunk size）；
- 单一视觉残差 → 视觉 + 跟踪误差双通道；
- 固定增益 → 按速度/加速度/接触相位调度；
- 单端口 → 多端口 deadline 调度；
- 5 次 A/B → STEP 序贯 + sham 对照 + 延迟注入。

**剪枝**：
- 「腕部无内参」假设删除（32/32 有内参）；
- 「在线改 chunk size」删除（metadata 固定）；
- 「从零训 VLA/World Model」删除（官方 WLA + 算力不划算）；
- 「6D 物体位姿网络」删除（透明/变形不可靠）；
- 「力/触觉闭环」删除（API 没有）；
- 「30Hz 广域网视觉伺服」删除（RTT 不允许）；
- 「第二个学习残差策略」删除（单模型风险）；
- 「把预览榜单当难度表」删除（已证伪）。

## 3. 竞赛策略：先修地基，再谈涨点

1. **W0（最高优先）**：延迟剖面 + 观测预算。先测「4 路 480p stack4」的真实 payload/p99，再决定是否降分辨率/减堆叠。**如果 p99 已经 >500ms，任何控制层创新都会被延迟吞掉。**
2. **W1**：AnyTime-Chunk + 进度对齐。用缓存 plan 吸收推理/网络抖动；用当前状态拼接剩余轨迹，减少 chunk 边界跳变。
3. **W2**：软截断 + 跟踪误差离线验证。先离线算 AUROC；不够就只保留软截断，不接接触检测。
4. **W3**：单任务通道 A/B + 延迟注入。用 STEP 序贯，不要固定 5 次就下结论。
5. **W4**：多端口调度 + 全量干跑。
6. **W5**：正式提交；保留回滚开关。

**任务组合**：优先接触密集 + 长任务（PlugInEthernet、ZipUp、ToolboxStorage、PackBag、OrganizePencilCase、HangCup、StackBowls）。这些任务的 30 步开环漂移最大（PlugInEthernet 0.162 rad），延迟/动力学收益最高。B 档任务（FruitSorting、ColorArrangement、FoldTowel）保留 VLA 基线，不强行加伺服。

**预算**：不要把正式 320 trials 当实验场；单任务通道做探索，正式评测做确认。每轮只改一个因子，预注册，算 MDE。

## 4. 一句话押注

**先押 AnyTime-Chunk + 进度对齐/软截断：它不依赖新模型、不违反单模型规则，直接利用本轮实测的 2–3 帧动作延迟和 0.08–0.16 rad 的 30 步开环漂移，把远程固定 chunk 从「1 秒开环」变成「预算内闭环」；观测带宽预算和多端口调度是它的放大器，跟踪误差检测是它的下一个增量。**

## 0. 结论与边界

### 0.1 一句话结论

在官方远程 API 的同步、固定 chunk 协议下，端到端反馈周期由「chunk 执行 + 观测上传 + 推理 + 排队 + 回传」共同决定；本轮实测/估算显示，动作与状态本身就有 2–3 帧（67–100ms）错位，30 步开环的状态漂移达 0.083–0.162 rad，而观测 payload 在示例配置下可达 0.45–4MB/请求。因此最划算的创新不是再换更大的 VLA，而是做一层 **PACE 执行中间件**：观测带宽预算（OBB）→ 预算内 AnyTime-Chunk → 进度对齐/软截断 → 动力学重定时 → 跟踪误差接触检测 → 多端口 deadline 调度；每一层都用预注册、序贯检验和阴性对照证明有效。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、代码、数据集元数据、排行榜 JSON、URDF 直接核实 | API 字段、`action_chunk_size` 固定、JPEG q95、32/32 腕部内参、G1 关节限制 |
| B | 我们在公开数据/网页上做的分析，可复现 | 动作-状态 lag、30 步开环漂移、快速/慢速跟踪误差、payload 量级估算 |
| C | 设计假设，需 G0–G8 验证 | 软截断 +10pp、跟踪误差 AUROC≥0.8、8 端口 p99≤500ms |

## 2. 问题形式化

### 2.1 延迟预算

设：

- `f_c`：evaluator 控制频率（本报告假设 30Hz，必须实测）；
- `H_c`：`action_chunk_size`（handshake 固定）；
- `T_obs`：观测采集 + JPEG 编码 + 上传；
- `T_infer`：VLA 推理；
- `T_q`：多端口共享 GPU 的排队；
- `T_ret`：动作回传 + evaluator 解析；
- `T_exec = H_c/f_c`：chunk 执行时间。

则端到端反馈周期：

```math
T_{\mathrm{fb}} = \frac{H_c}{f_c} + T_{\mathrm{obs}} + T_{\mathrm{infer}} + T_q + T_{\mathrm{ret}}.
```

观测 payload：

```math
B = \sum_{k \in \mathcal{K}} N_{\mathrm{stack}}(k)\,H_k W_k\,\mathrm{bpp}(H_k,W_k,\text{content}),
\qquad
T_{\mathrm{obs}} \approx \frac{B}{U} + T_{\mathrm{enc}}.
```

其中 `U` 是上行带宽，`bpp` 是每像素比特数。官方 JPEG q95/4:4:4 的 `bpp` 对自然图像约 1.5–3 bits/px；复杂桌面图可能更高。

**量级估算**（用 640×480 自然图像按 q95/4:4:4 量级转码，2026-10-31；真实桌面图会更大）：

| 分辨率 | 单帧 JPEG | 4 路×1 帧 | 4 路×2 帧 | 4 路×4 帧 |
|---|---:|---:|---:|---:|
| 640×480 | 28.3 KB | 0.11 MB | 0.22 MB | 0.43 MB |
| 320×240 | 9.5 KB | 0.04 MB | 0.07 MB | 0.14 MB |
| 256×192 | 7.5 KB | 0.03 MB | 0.06 MB | 0.11 MB |
| 128×128 | 3.0 KB | 0.01 MB | 0.02 MB | 0.05 MB |

**注意**：这是简单自然图像的估算；真实机器人桌面图可能大 2–5 倍。按 4 路×4 帧、复杂图 100–250KB/帧计算，payload 可达 **1.6–4MB/请求**；10Mbps 上行对应 **1.3–3.2s**，50Mbps 对应 **0.26–0.64s**。**如果评测环境上行只有 10–50Mbps，观测上传就是主延迟，而不是 6B 推理。**

**排队模型**：设每端口请求率 `λ = 1/(T_exec + T_obs + T_infer + T_ret)`，GPU 服务率 `μ = 1/E[S]`，服务强度 `ρ = λ/μ`。M/M/1 近似：

```math
E[W_q] = \frac{\rho}{1-\rho}E[S],\qquad
P(W_q > t) \approx \rho e^{-(\mu-\lambda)t}.
```

当 `ρ→0.8` 时，`E[W_q]=4E[S]`；`ρ=0.9` 时 `9E[S]`。**多端口共享 GPU 时，p99 排队延迟会在 ρ>0.8 后爆炸；必须把并发/分辨率/批处理一起设计。**

### 2.2 动力学可行性

对每个关节 `j`，动作序列 `q_{0:H}` 需满足：

```math
q_j^{\min} \le q_{j,k} \le q_j^{\max},
\qquad
|q_{j,k+1}-q_{j,k}| \le \frac{v_j^{\max}}{f_c},
\qquad
|q_{j,k+1}-2q_{j,k}+q_{j,k-1}| \le \frac{a_j^{\max}}{f_c^2}.
```

G1 的 `v_max` 为 22–37 rad/s（手臂），`a_max` 需要从数据/URDF/实验估计；本报告用数据中的 p95 加速度（39–79 rad/s²）作为保守先验，实际限幅应更保守（例如 0.5×）。

跟踪误差：

```math
e_{\mathrm{track}}(t) = q_{\mathrm{actual}}(t+1) - q_{\mathrm{cmd}}(t).
```

在自由空间，`e_track` 是速度、姿态、负载、摩擦的函数；在接触时，外部力矩会改变它。用速度分箱的标准化残差：

```math
r(t) = e_{\mathrm{track}}(t) - \mathbb{E}[e_{\mathrm{track}} \mid v_{\mathrm{bin}}(t)],
\qquad
s(t) = \frac{\|r(t)\|}{\sigma_{\mathrm{bin}}+\epsilon}.
```

`s(t)` 超过阈值 `θ_c` 且持续 `K` 帧 → 接触/滑移/干扰候选。

### 2.3 软截断与有效 horizon

固定 chunk `H_c` 内，定义风险分数：

```math
R_k = w_1\,\hat{p}_{\mathrm{contact},k} + w_2\,\|e_{\mathrm{track},k}\| + w_3\,d_{\mathrm{target},k} + w_4\,\mathrm{age}(\mathrm{plan}),
```

其中 `d_target` 来自视觉/几何接近度（第 12 轮），`age(plan)` 是 plan 的时间戳。找到第一个 `R_k > θ_r` 的索引 `k*`，把 `k*` 之后替换为制动到保持位姿的轨迹：

```math
q_{k^*+\tau} = q_{k^*} + v_{k^*}\,T\,(1-e^{-\tau/T}),\qquad \tau=1,\dots,H_c-k^*,
```

并做限幅/限速。这样 evaluator 仍执行 `H_c` 步，但机器人实际在 `k*` 后减速/停住，等效 horizon 为 `H_eff=k*`。

**为什么不在线改 chunk size**：`action_chunk_size` 是 metadata 常量；返回不同长度的数组会被 `ExampleEnv` 拒绝。软截断是唯一合规的「有效 horizon」手段。

### 3.3 AnyTime-Chunk 伪代码

```python
class PACEPolicy:
    def __init__(self, vla, token, budget_ms=220, H_c=8):
        self.vla = vla
        self.token = token
        self.budget = budget_ms / 1000.0
        self.H_c = H_c
        self.plan = None          # (H, D) absolute or relative actions
        self.plan_idx = 0
        self.plan_ts = 0.0
        self.future = None
        self.executor = ThreadPoolExecutor(max_workers=1)

    def get_action(self, obs):
        now = time.monotonic()
        self._observe(obs)
        self._maybe_start_inference(obs)

        deadline = now + self.budget
        plan = self._select_plan(deadline)
        if plan is None:
            return self._safe_hold(obs)

        q_act = self._current_state(obs)
        aligned = progress_align(plan, q_act, self.plan_idx)
        risk = self._risk(obs, aligned)
        if risk > self.theta_trunc:
            aligned = soft_truncate(aligned, risk)
        if self._contact_score(obs) > self.theta_contact:
            aligned = slow_normal(aligned, factor=0.5)
        aligned = d_retime(aligned, self.limits)

        self.plan_idx += self.H_c
        if self.plan_idx >= len(plan):
            self.plan = None
        return self._to_api(aligned)

    def _maybe_start_inference(self, obs):
        if self.future is not None and not self.future.done():
            return
        if self.future is not None:
            self.plan = self.future.result()
            self.plan_ts = time.monotonic()
            self.plan_idx = 0
            self.future = None
        if self.plan is None or (time.monotonic() - self.plan_ts) > self.plan_ttl:
            snapshot = copy_obs(obs)
            self.future = self.executor.submit(self.vla.predict, snapshot)

    def _select_plan(self, deadline):
        if self.future is not None:
            try:
                self.plan = self.future.result(timeout=max(0.0, deadline - time.monotonic()))
                self.plan_ts = time.monotonic()
                self.plan_idx = 0
                self.future = None
            except TimeoutError:
                pass
        return self.plan
```

### 3.4 进度对齐伪代码

```python
def progress_align(plan, q_act, plan_idx, blend=3):
    # 1) find the plan point closest to the actual state (phase estimate)
    k0 = min(range(len(plan)), key=lambda k: dist(plan[k], q_act))
    # 2) keep the future path, but start from the actual state
    out = plan.copy()
    # 3) C1/C2 blend: quintic from q_act (v=0) to plan[k0+blend] (v=plan velocity)
    p0, v0 = q_act, np.zeros_like(q_act)
    p1 = plan[min(k0 + blend, len(plan) - 1)]
    v1 = (plan[min(k0 + blend + 1, len(plan) - 1)] - plan[min(k0 + blend - 1, 0)]) * 0.5
    for t in range(blend):
        s = (t + 1) / blend
        out[k0 + t] = quintic(p0, v0, p1, v1, s)
    return out
```

注意：如果使用 `ee` 模式，`q_act` 换成当前 EE 位姿；四元数/旋转向量要做球面插值。修正幅度限幅：每 chunk 平移 ≤1cm、旋转 ≤0.05rad，避免压过 VLA 的语义意图。

### 3.5 软截断伪代码

```python
def soft_truncate(plan, risk, q_act, v_max, a_max):
    k_star = first_index_above(risk)
    if k_star is None or k_star >= len(plan) - 1:
        return plan
    out = plan.copy()
    p_hold = plan[k_star]
    v_hold = np.zeros_like(p_hold)
    for t in range(k_star, len(plan)):
        # exponential braking to hold, respecting limits
        s = (t - k_star + 1) / max(1, len(plan) - k_star)
        out[t] = smooth_brake(plan[k_star], p_hold, s)
    return project_to_limits(out, v_max, a_max)
```

### 3.6 跟踪误差接触检测伪代码

```python
def contact_score(obs, prev_cmd, stats):
    q_next = obs["observation.state.left_arm"]     # actual at t+1
    e = q_next - prev_cmd                           # 7-dim tracking error
    v = np.linalg.norm(q_next - stats.prev_q) * 30  # speed
    b = stats.speed_bin(v)
    r = e - b.mean
    s = np.linalg.norm(r) / (b.std + 1e-6)
    stats.ema = 0.7 * stats.ema + 0.3 * s
    return stats.ema
```

```python
def schedule(requests):
    # requests: (port_id, deadline, obs_bytes, session)
    requests.sort(key=lambda r: r.deadline)          # EDF
    batch = []
    now = time.monotonic()
    for r in requests:
        if len(batch) >= B_max:
            break
        if r.deadline - now < min_service_time:
            # starvation: return soft-truncated cached chunk instead
            mark_starved(r.port_id)
            continue
        batch.append(r)
    return batch

def lookahead(port_states, candidate_batch):
    # Armory-style: simulate each port's action-buffer depletion
    # prefer batches that protect ports close to starvation
    return argmax(batch for batch in candidates
                  if min_remaining_steps(port_states, batch) is maximized)
```

## 4. 子模块推导与预算

### 4.1 OBB 的帕累托

目标：在成功率不降 >2pp 的前提下，把 `T_obs` 降 ≥50%。候选：

| 配置 | 相机 | 分辨率 | 堆叠 | 估算 payload（简单图/复杂图） | 风险 |
|---|---|---|---:|---:|---|
| A（基线） | 4 路 | 480×640 | 4 | 0.43MB / 1.6–4MB | 延迟最高 |
| B（平衡） | 3 路（头左+双腕） | 320×240 | 2 | 0.06MB / 0.2–0.6MB | 丢头右深度 |
| C（极简） | 3 路 | 256×192 | 1 | 0.03MB / 0.1–0.3MB | 细节/动态不足 |

注意：如果 VLA 需要头双目做深度，B/C 可能伤精度；可以声明 4 路但把 `cam_right_high` 降到 128×128，策略内部不用它做语义，只做深度。**这是提交前必须做的消融，不是拍脑袋。**

### 4.2 AnyTime-Chunk 的收益条件

设推理时间 `T_infer` 的分布为 `F`，预算 `B`。若 `B < T_infer`，会频繁用旧 plan；若 `B > T_exec`，evaluator 会等待，失去意义。合理选择：

```math
B \approx \min(T_{\mathrm{exec}},\ \mathrm{p95}(T_{\mathrm{obs}}+T_{\mathrm{infer}}+T_{\mathrm{ret}})).
```

如果 `T_exec=8/30=267ms`，p95 端到端 220ms，则 `B≈220ms`；这样大多数请求能拿到新 plan，少数超时用旧 plan + 软截断。**B 不是越短越好；要用实测分布选。**

### 4.3 D-RETIME 的时间缩放

对路径 `q(s)`，时间缩放 `s(t)` 需满足：

```math
\dot{s} \le \min_j \frac{v_j^{\max}}{|q_j'(s)|},\qquad
\ddot{s} \le \min_j \frac{a_j^{\max}}{|q_j''(s)|}.
```

简化实现：对每个 chunk 离散检查，若违反则整段乘以 `γ<1`（放慢），二分找最大可行 `γ`；然后做限幅。接触段额外乘 `0.5`。**不要做全局慢放**：数据显示自由段速度只有 0.14–0.22 rad/s，远低于 37 rad/s，慢放会浪费 180s 预算。

### 4.4 T-CONTACT 的可辨识性

跟踪误差残差不是力传感器；它只能检测「关节实际位置偏离指令」的事件。可辨识条件：

1. 关节在运动（速度 > 阈值），否则静摩擦/重力补偿会掩盖接触；
2. 接触力在关节上产生可测力矩（腕 pitch/yaw 力矩上限只有 5 N·m，敏感但易饱和）；
3. 控制器是位置/PD 控制，接触会导致跟踪误差；
4. 没有同时发生快速加速度变化（需按速度/加速度分箱）。

如果 AUROC<0.8，T-CONTACT 只做离线分析/可视化，不接线上触发。**这是 G4 的 kill criterion。**

### 4.5 MP-Serve 的并发预算

粗略：6B bf16 权重约 12GB；一张 24GB GPU 只剩 ~10GB 给 KV/激活/批处理。单端口 4 路图 + 30 步动作，batch=4 可能就接近上限。**不要假设一张 24GB 卡能服务 8 端口同时推理；** 要么用 40/80GB 卡，要么降分辨率/减少 batch，要么用 8bit 量化（需验证精度）。MP-Serve 的调度只能缓解排队，不能创造显存。

## 5. 实验设计

### 5.1 预注册模板

在跑单任务通道前写下：

```text
假设 H1：在 PlugInEthernet/ZipUp/HangCup 上，progress-align + soft-trunc 的 10 次成功率高于 raw chunk ≥10pp。
主要终点：任务成功率（10 trials/任务，按官方泛化类型分层）。

停止规则：STEP 后验概率 >0.95 或达到最大次数。
排除标准：接口错误、token 错误、非策略原因的硬件故障。
```

### 5.3 样本量与 MDE（必须事先算）

未配对两比例（α=0.05, power=0.8）：

```math
n_{\text{per group}} \approx \frac{(z_{\alpha/2}+z_\beta)^2\,[p_1(1-p_1)+p_2(1-p_2)]}{(p_1-p_2)^2}.
```

| p1→p2 | 每组所需 n | 结论 |
|---|---:|---|
| 0.25→0.30（+5pp） | ≈1247 | 320 trials 远远不够 |
| 0.25→0.35（+10pp） | ≈326 | 320 trials 勉强 |
| 0.25→0.40（+15pp） | ≈149 | 可检测 |

**正式 320 trials 的整体 SE≈2.4pp，95% CI≈±4.7pp；它只能检测 ≥10pp 的大效应。** 单任务 10 trials 的 95% CI 约 ±30pp，几乎不能检测任何小效应。**所以：**

- 小效应（+2–5pp）只能在单任务通道用配对/重复测量/序贯检验；不能靠正式评测证明。
- 榜单上 29.7% 与 25.9% 的 3.8pp 差距，在 10 trials/任务、320 trials 的噪声下并不显著；不要过度解读排名。
- 如果单任务通道不支持固定初始条件，配对优势消失；退化为分层/重复测量，所需样本更大。**必须先邮件确认单任务通道的初始条件控制能力。**

### 5.4 阴性对照（sham controls）

| 对照 | 做法 | 排除的假阳性 |
|---|---|---|
| Sham servo | 随机方向/幅度的修正，幅值与真伺服相同 | 「任何动作扰动/更多运动」带来的收益 |
| Sham retime | 随机时间缩放，不改路径 | 「单纯变慢」带来的收益 |
| Delay placebo | 注入延迟但不改策略 | 延迟本身的伤害，而不是策略的收益 |
| No-op fill | 用保持动作填充 chunk 后半段 | 「软截断」与「VLA 后半段」的贡献分离 |
| Config placebo | 同样 payload 但随机丢帧 | 分辨率/堆叠的收益是否只是正则化 |

### 5.5 方差分解

用混合效应模型：

```math
y_{ijkl} = \mu + a_i + b_j + c_k + d_l + \epsilon_{ijkl},
```

`a`=任务，`b`=场景/泛化类型，`c`=机器人/端口，`d`=网络/延迟，`ε`=trial。用 pilot 估计 ICC；如果网络方差占比 >20%，优先做 OBB/MP-Serve；如果任务方差占主导，优先做任务组合。

| S0 | lag / speed / task | 0–5 帧；慢/快；3 任务 | 跟踪误差、开环漂移、AUROC |
| S1 | policy × RTT | raw/align/trunc/both；0/50/100/150ms | 成功率、收敛、超调 |
| S2 | config × policy | A/B/C × 4 策略 | 成功率、步骤分、p99 |
| S3 | ports × config | 1/2/4/8 × 最佳配置 | p99、starvation、显存 |
| S4 | 全量 | 32×10 | 总成功率、步骤分、超时 |

## 6. 竞赛策略

### 6.1 任务优先级（先验，待单任务通道更新）

| 档 | 任务 | 理由 |
|---|---|---|
| P0 接触密集/长任务 | PlugInEthernet、ZipUp、ToolboxStorage、PackBag、OrganizePencilCase、HangCup、StackBowls | 30 步开环漂移大（PlugInEthernet 0.162 rad）；软截断/重定时收益最高 |
| P1 位置/人为干扰 | 5 类泛化轴；human 2/10 | AnyTime-Chunk + 进度对齐抗延迟/扰动 |
| P2 语义/变形/动态 | FruitSorting、ColorArrangement、FoldTowel、ConveyorSorting | 保留 VLA 基线；不强行加几何伺服 |
| P3 低投入/观察 | 单任务通道 p_t≈0 且失败在早期感知 | 不投入执行层工程 |

优先级公式：

```math
\mathrm{priority}_t = \frac{q_t \cdot \Delta_t}{\mathrm{cost}_t},
```

`q_t`=失败发生在最后 3 厘米/最后 300ms 的比例（先验，单任务通道更新）；`Δ_t`=执行层条件增益；`cost_t`=工程/评测成本。

### 6.2 时间表

| 周 | 交付 | 退出条件 |
|---|---|---|
| W0 | 延迟剖面 + OBB 帕累托 | G0/G1 |
| W1 | AnyTime-Chunk + progress-align | G2 |
| W2 | soft-trunc + T-CONTACT 离线 | G3/G4 |
| W3 | 单任务 A/B + 延迟注入 | G5/G7 |
| W4 | 多端口调度 + 全量干跑 | G6 |
| W5 | 正式提交 + 回滚开关 | G8 |

### 6.3 资源

- 1×24GB GPU（WLA 微调/单端口推理）；1×40/80GB（多端口，可选）。
- 16–32 CPU 核（每端口 PolicyService、观测编解码、离线回放）。
- 存储：3 个任务 parquet 约 300MB；全量视频按需缓存。
- 人员：1 人执行层/控制；1 人 VLA/部署；1 人评测/统计；可兼职。

### 6.4 提交节奏

1. 先交「安全基线」：官方 WLA + 原始 chunk + 保守配置，锁更早提交的 tie-break（若允许多次提交）。
2. 再交 PACE v1：OBB + AnyTime + progress-align。
3. 最后交 PACE v2：+ soft-trunc + T-CONTACT + MP-Serve。
4. 每次提交前跑 G0–G8；没有过门不烧正式 trials。
5. 若只允许一次提交：跳过基线提交，直接用单任务通道把 v1/v2 打磨到稳定。

## 7. 风险与合规

### 7.1 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 跟踪误差/接触标签只离线用；线上只有 VLA | 最低 | 保守首选 |
| C2 确定性控制器 | 进度对齐、软截断、重定时、阈值检测都是控制器，无学习权重 | 低；需说明 | 主推 |
| C3 同 checkpoint 特征 | 若需要描述子，用同一 VLA encoder | 低–中 | 需要强描述子时用 |

**禁止**：加载第二个学习策略/残差网络/独立视觉编码器做在线决策；用离线数据训练一个接触分类器（除非归为 C1 只做离线）。

### 7.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判第二个模型 | C1/C2；所有在线模块无学习权重；提交材料写清楚 |
| 无 evaluator 时间戳 | 延迟估计不准 | 用请求间隔/chunk 执行时间反推；注入延迟做标定；保守预算 |
| 观测降分辨率伤精度 | 成功率下降 | 帕累托实验；保留头双目；腕部局部 ROI |
| 软截断未完成任务 | 成功率下降 | 只在高风险段；限幅；保留 VLA 后半段回退 |
| 进度对齐改变意图 | 任务偏移 | 修正幅度 ≤1cm/0.05rad/chunk；置信度低回退 |
| 动力学模型不准 | 违规/超调 | URDF + 数据标定；保守限幅；仿真风洞 |
| 跟踪误差信号弱 | 误报/漏报 | 速度分箱；EMA；AUROC 门；不够就砍 |
| 多端口显存不足 | OOM/排队 | 降分辨率/批大小；40/80GB；8bit 量化需验证 |
| 单任务通道不能配对 | 统计功效低 | 邮件确认；分层/重复测量；仿真配对 |
| 正式 trials 只能检测大效应 | 误判 +2pp | 预注册 + STEP + 效应量；不吹小效应 |
| 数据泄漏 | 离线指标虚高 | 按 session/任务/物体划分；相邻帧不跨 split |
| 手眼外参未标定 | 伺服/对齐偏差 | 一次棋盘格/演示重投影；置信度低回退 |
| 提交次数限制 | 无法多次 A/B | 邮件确认；单任务通道先验证；一次提交则保守 |
