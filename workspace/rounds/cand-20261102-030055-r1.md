# 第 13 轮 · RUBRIC-LORA：把官方 94 个评分步骤变成密集监督，用 LoRA 组合实验并合并成单模型，再用 5 步伺服补最后 3 厘米

> 检索/复核日期：**2026-11-02（UTC）**。赛事身份已核实：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），Unitree G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新一轮灵感循环第 1 轮，三个词是「竞赛策略」「移动操作」「LoRA」。本轮不推倒第 12 轮 **CHUNK-SERVO**，而是补齐它缺的两层：**训练/选择层（官方 rubric + LoRA 组合）** 和 **接口/全身层（pivot/height 适配）**。

## 0. 先给结论：榜单不可信，但 rubric 和 LoRA 是真的

### 0.1 榜单 29.7% 不能当 SOTA

截至 **2026-11-02**，官网首页和排行榜页的可见文本仍出现「即将发布 Coming Soon」，详情页 32 个任务视频全部是「测试视频占位，后续可替换为真实视频文件」。但同一站点仍能抓到 `leaderboard_data.json`，其中 8 个模型、32 个任务，MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。

这份 JSON 有明显生成痕迹，本轮重新验证：

- `generated_from` 是 `gen_leaderboard.py`；
- 8 个模型 × 32 任务，`step_score ~ success_rate` 回归 **R² > 0.999999**，最大残差 < 0.006；
- 每任务只有 10 次 trial，但 256 个 task-success 里有 **232 个不是 10% 的整数倍**（如 27.29%、27.85%）；
- 8 个模型的 32 维任务成功率两两相关，平均 off-diagonal 只有 **0.0975**；
- JSON 的任务名是旧版/旧 slug，和当前 `tasks_v2` 的 32 任务集并不完全一致。

**结论**：29.7% 只能当赛事方的「预览上限/难度信号」，不能当 SOTA、任务难度表或失败分布。本轮不从榜单任务排名里挖创新点；只从公开模型家族的路线、官方 rubric、官方数据和 LoRA 工具链里挖。

### 0.2 真正的富矿：32×100 分、94 个评分步骤

官方 32 个 `tasks_v2/<slug>/info.json`（2026-11-02 逐个抓取）给出：

- 32 个任务，每个任务满分 **100 分**，总分 **3200 分**；
- 共 **94 个评分步骤**，每任务 2–5 步；
- 步骤权重只有 5 种：**20 / 25 / 30 / 40 / 50**；
- 难度：Easy 12 / Medium 12 / Hard 8；
- 每个任务还有 `generalization` 字段，明确写出 `human_1_note`、`human_4_note`、`unseen_object_3` 的具体扰动。

例：T01 HangCup 是「抓住杯把 50 分 → 挂到杯架标记位置 50 分」；T19 ZipUp 是「摆正收纳包 50 分 → 拉上拉链 50 分」；T16 FoldTowel 是 5×20 分；T09 ToolboxStorage 是 4×25 分。

这不是「32 个 0/1」，而是一个**免费的子目标图 + 权重表**。当前大多数模型只优化动作 MSE 或整段成功率，没有把这个 rubric 用起来。这是本轮第一个创新切入点。

### 0.3 LoRA 已经不是瓶颈，执行和选择才是

官方 UnifoLM-WLA 仓库（2026-11-01 更新）已经明确支持 LoRA：

- `trainer.lora` 可分别作用于 `qwen_vl_interface`（VLM）和 `action_model`（DiT action head）；
- 默认 `r=16`、`lora_alpha=32`、`lora_dropout=0.05`；
- 只输出 adapter-only checkpoint（`adapter.safetensors`），单张 **24GB** GPU 可跑；
- 默认 20,000 steps、batch 1、gradient accumulation 8、lr 1e-4；
- VLM 可冻结，action head 用 LoRA 替代全参微调。

公开的 UniBot LoRA 复现也证明可行：`ezhoureal/lingbot-vla-v2-unibot-lora` 用 LingBot-VLA 2.0（6.3B：Qwen3-VL-4B + Qwen2 action expert MoE）在 **32 任务、33,276 episodes** 上做 rank 64、alpha 32 的 LoRA，10K steps，**单张 RTX 4090**，最终把 LoRA **合并进 base weights**，导出一个 full-model safetensors；ArrangePlates 开环验证 MSE 0.229 / MAE 0.176，约 **0.35 s / 50-step chunk**。

这条路线的含义：

1. **训练成本不再是大门槛**：单卡 24GB/4090、10K–20K steps 就能做一次全数据适配。
2. **LoRA 本身不解决接触精度**：公开复现用的是 **50 步 chunk**，按 30Hz 就是 1.67 秒开环，比 WLA 默认 30 步还长；开环 MSE 低不等于真机成功率。
3. **真正稀缺的是「试错次数」和「选择标准」**：单任务不计分通道的评测时段有限，必须用 LoRA 快速做多方案，再用 rubric/离线指标筛选，最后合并成一个提交模型。

### 0.4 「移动操作」在数据里几乎不存在：不要造移动底盘

本轮抽样检查了 32 个数据集各前 100 帧的 `action.base_command`：

- `vx`、`vy`、`angle_z` 的最大绝对值 **< 2.5e-12**，即全部为 0；
- `height` 在 **0.689–0.740 m** 之间，少数任务（如 ArrangeTestTubes、PaperCupStacking、Unlock、PickOutBatteries）会降低；
- `action.pivot` 的 7 维字段名是 `vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height`，其中 `pivot_4` 在样本中为 0 或 0.15，`pivot_3/5` 为 0。

这说明：**当前 UniBot-V1 是固定底座的桌面操作 benchmark，不是移动操作 benchmark。** 训练数据里没有 base 平移/转向；human 注释里的「动底座」更可能指物体底座/托盘，而不是机器人底盘。把工程投到移动底盘、SLAM、导航是错配。

但「移动操作」可以合法地降级为两件事：

- **全身可达性**：用 `pivot` 的 height/waist/躯干维度，扩大桌面边缘、低处、高处的可达范围；
- **被移动后的恢复**：如果人或场景把物体/底座移动了，用视觉残差重新定位，而不是靠底盘里程计。

这是本轮第二个重要修剪：**PIVOT-REACH，不造移动底盘。**

### 0.5 本轮押注

**RUBRIC-LORA = RUBRIC-GRAPH（官方 94 个评分步骤 → 数据加权/验证指标/任务组合）+ LORA-PORTFOLIO（6–8 个 LoRA 候选 → TIES/DARE 合并 → 单一提交模型）+ CHUNK-SERVO（30 步规划 + 5 步闭环执行）+ PIVOT-REACH（只动 height/waist，不动 base）。**

一句话：**用官方 rubric 决定「练什么、先测什么」，用 LoRA 决定「多快能试完」，用合并后的单一适配器提交，用 5 步伺服解决最后 3 厘米。**

### 1.3 LoRA：官方工具链 + 公开 UniBot 复现

官方 `docs/train_action_expert_en.md`（2026-11-02 抓取）明确：

- `trainer.lora.enabled`，可分别启用 `qwen_vl_interface` 和 `action_model`；
- 默认 `r=16`、`alpha=32`、`dropout=0.05`；
- action model 的目标模块包括 `to_q/to_k/to_v/to_out.0/add_q_proj/add_k_proj/add_v_proj/to_add_out`；
- 只保存 adapter-only checkpoint，适合分发；
- 单张 24GB GPU 可跑；VLM 冻结时只训 DiT action head + robot-state projector。

公开的 `ezhoureal/lingbot-vla-v2-unibot-lora`（2026-08-02 创建）给出另一条实证：

- 6.3B LingBot-VLA 2.0，rank 64、alpha 32，`q_proj/v_proj/o_proj`，65M trainable；
- 32 任务、33,276 episodes 全量；
- 10K steps，单张 RTX 4090，bf16 model + fp32 LoRA；
- 最终 LoRA **合并进 base weights**，单个 full-model safetensors；
- 控制空间是 joint：双臂 14 + 夹爪 2 + waist 4 + base 3；
- `use_length=50`，50 步 chunk，约 0.35 s/chunk；
- ArrangePlates 开环 MSE 0.229 / MAE 0.176。

这条公开复现同时证明了两件事：**LoRA 全数据适配在单卡上可行；但 50 步 chunk 的开环执行是新的瓶颈。** 它没有给出真机成功率，因此不能把开环 MSE 当作竞争力。

### 1.4 接口：pivot 字段名与 base 的真实使用

`unibot_submission` README（2026-11-02）给出：

- `action.pivot` 形状 `[7]`，描述为 lower-body / pivot target，但**没有逐维定义**；
- `observation.state.lower_body` 形状 `[15]`：左右腿各 6 + `waist_yaw/roll/pitch`；
- `observation.state.left_ee_pose_gripper_base` / `right_...`：base 系 xyz+rpy；
- 没有 depth、camera_info、force/torque、tactile；
- `action_chunk_size` 固定，chunk 内没有新观测、没有打断机制。

数据集 `meta/info.json` 给出 `action.pivot` 的 7 个字段名：`vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height`；`action.base_command` 是 4 维：`vx, vy, angle_z, height`。

本轮抽样 32 个数据集各前 100 帧：

- `base_command` 的 `vx/vy/angle_z` 全部为 0；
- `height` 在 0.689–0.740 m；
- `pivot_4` 在部分任务为 0.15，部分为 0；`pivot_3/pivot_5` 为 0。

**推断**：当前任务的「移动」主要不是底盘移动，而是高度/躯干/腰部的调整。`pivot_3/4/5` 的语义官方没有写清楚，必须用 `example_env.py` 和单任务通道验证，不能猜。

### 1.6 头部方案与公开复现的瓶颈

| 模型/路线 | 公开做法 | 优势 | 与最后 3 厘米相关的瓶颈 |
|---|---|---|---|
| **MolmoAct2** | action reasoning + adaptive depth + 大规模双臂数据 | 3D/空间语义强、推理快 | 仍是长 action chunk；接触段开环 |
| **WALL-OSS-0.5** | 4B VLA（3B VLM + action expert） | 预训练可用、progress 高 | progress ≠ success；终局一步失败就 0 |
| **DreamZero** | 14B video-diffusion world-action model | 长程预测 | 推理重、chunk 更长；世界模型不解决 2mm 偏差 |
| **π0.5** | 开放世界泛化 VLA | 语义/新场景泛化 | 接触密集任务精度、远程延迟 |
| **GigaBrain-0** | 世界模型生成数据 + VLA | 数据效率 | 生成数据物理保真度；最后 3 厘米 |
| **GR00T N1.5** | 通用人形 VLA | 生态/embodiment | 任务特定精度、数据覆盖 |
| **公开 LingBot LoRA** | 6.3B + rank 64 LoRA + 合并 | 单卡可训、全数据、单一 checkpoint | 50 步 chunk、无闭环、开环 MSE 不等于成功率 |

共同点：**没有一个是「接触闭环」模型；模型越大/chunk 越长，越不反应。** 这正是 CHUNK-SERVO 仍然成立的理由。

## 2. 诊断：四个错配

1. **训练目标错配**：大多数 VLA 优化动作 MSE 或整段成功率；官方 rubric 有 94 个带权子目标，但没有被用作采样权重、验证指标或伺服触发。结果是「平均动作像」但「高权重终局步骤不稳」。
2. **实验速度错配**：全参微调成本高，导致只敢做 1–2 个方案；LoRA 已经把单次实验压到单卡 10K steps，但如果只做「一个大 LoRA」，仍然没有利用 LoRA 的并行试错优势。
3. **执行频率错配**：30 步（WLA）或 50 步（公开 LoRA）chunk 内不看新图；接触发生在 chunk 内部时，只能等下一个 chunk。模型越大，越倾向长 chunk，越不适合最后 3 厘米。
4. **移动操作错配**：数据里 base 平移/转向为零；把工程投到移动底盘是浪费。真正的「移动」是 pivot/height/waist 的可达性，以及物体被移动后的视觉恢复。

## 3. 创新点清单（本轮深化与修剪）

> 说明：这是跨轮保留的清单，不是本轮从零开始。状态分为「主投 / 保留 / 新增 / 降级 / 剪枝」。

### P0 · API-ADAPTER：先把 WLA/LoRA 接到挑战赛接口（必做，不算研究创新）

- **动机**：官方 WLA model server 明确是 Dex1-only，且 `model_server/unifolm_wla_action_adapter.py` 的 `_ACTIVE_SLOT_SPECS` 与 `active_rot6d_to_wbc50` 里引用的 `left_fig6d/right_fig6d` 并不一致；挑战赛 API 又是 2×6 EE + 2×1 gripper + 7 pivot，不能直接复用。
- **与现有方案差异**：不是再训模型，而是把「相对 EE → 绝对 EE、rpy↔rot6d、54D→21D、chunk 切片、token/reset 隔离」做成可单测的 adapter。
- **技术可行性**：高。WLA 文档给出 54D 布局；GitHub issue #16 确认 EE 是 pelvis base、Dex1 偏移 `[0.105, 0, 0]`；挑战赛 `example_env.py` 可做 shape/dtype/token 校验。
- **所需资源**：1–2 人周；1 张 24GB GPU 做推理；无需新数据。
- **落地步骤**：① 用 `example_env.py` 跑通 `joint` 与 `ee` 两种 control space；② 写 54D→21D adapter；③ 用真实 episode 做 EE 重投影/位姿误差检查（≤1 cm / 2°）；④ 先返回零 pivot、只验证双臂；⑤ 单任务通道跑 1 个任务。
- **风险**：pivot 语义不明、EE 帧差一个 TCP 偏移、chunk 锚点 compose 错、官方 server 与挑战赛状态键不一致。
- **状态**：必做；不过门不进入任何学习实验。

### P1 · RUBRIC-GRAPH：把 94 个评分步骤变成密集监督和任务组合（新增，主投）

- **动机**：官方 rubric 已经给出每个任务的子目标、顺序和权重；当前模型只优化整段动作/成功率，没有利用「哪一步值 50 分、哪一步最容易丢」。
- **与现有方案差异**：不是再训一个 progress classifier；而是把 rubric 同时用于 **数据采样权重、验证指标、伺服触发、竞赛任务排序**。与第 10 轮 FACT-VLA 的相位分割相比，这里用官方评分点作为弱标签和权重，而不是纯无监督分段。
- **技术可行性**：高。32 个 `info.json` 可直接解析；94 个步骤可人工校对；与现有 episode 的对齐可以先用时间/相位启发式，再用少量人工标签。
- **所需资源**：1 人周做解析/对齐/QA；CPU 即可；可选一个轻量 progress head（与 action head 同一 checkpoint，合规）。
- **落地步骤**：① 解析 32×steps，建立 `(task, step, weight, terminal?)` 表；② 用 FACT-VLA/GEO-RESIDUAL 把成功 episode 分段并对齐到 rubric；③ 生成帧级/阶段级权重；④ 用权重做 LoRA 采样和 rubric-weighted 验证；⑤ 用单任务通道的 step score 校准；⑥ 用 `terminal_weight × near_miss / cost` 排任务优先级。
- **风险**：rubric 有人工评分主观性；步骤边界模糊；step score 不是 API 逐步返回；过度加权终局会让模型跳过前置步骤。
- **状态**：新增，主投；先做离线版，不急于上线 progress head。

### P2 · LORA-PORTFOLIO：多 adapter 快速实验，TIES/DARE 合并成一个提交模型（新增，主投）

- **动机**：官方 LoRA 单卡 24GB、公开复现单卡 4090 10K steps；评测时段有限，必须用「多方案训练 + 少样本选择」替代「一个大模型硬调」。
- **与现有方案差异**：不是推理时多 LoRA 路由（有单模型合规风险），而是**离线训练 6–8 个候选 adapter，按 rubric/离线/单任务通道选择，再合并成一个 checkpoint 提交**。也不是 32 个任务各训一个策略。
- **技术可行性**：中高。官方脚本可直接用；LoRA rank 16–64、10K–20K steps、单卡可跑；TIES/DARE 是成熟模型合并方法；公开 UniBot LoRA 已证明「合并成单模型」可导出。
- **所需资源**：1–2 张 24GB/40GB GPU；2–4 周；1–2 TB 存储；若干单任务评测时段。
- **落地步骤**：① 定义 6–8 个数据/架构轴（全任务均衡、Hard-8 过采样、终局 50 分任务、human 扰动增强、背景/干扰物/未见物品增强、joint vs ee、action-head vs VLM LoRA、chunk 5/10/30）；② 每个轴训一个 LoRA；③ 用 rubric-weighted 离线误差 + 3–5 个单任务通道筛 top-3；④ TIES/DARE 合并；⑤ 合并模型全任务回归；⑥ 若合并退化 >2pp，回退到单个多任务 LoRA。
- **风险**：LoRA 欠拟合/合并冲突；单模型合规解释；评测成本；离线 MSE 与真机 success 脱节；VLM LoRA 过拟合 32 任务、伤泛化。
- **状态**：新增，主投；与 P1 绑定成 RUBRIC-LORA。

### P3 · CHUNK-SERVO：30 步规划 + 5 步闭环执行（保留，升级）

- **动机**：第 12 轮已论证最后 3 厘米的开环问题；公开 LoRA 的 50 步 chunk 进一步说明「模型越大/chunk 越长越不反应」。
- **与现有方案差异**：本轮不重做，只加两点：① 腕部内参已知，IBVS 成本下降；② 用 RUBRIC-GRAPH 做**分数感知触发**——只在接近高权重终局步骤或视觉残差大时启用伺服，其他时候保持 VLA 开环以省延迟。
- **技术可行性**：中高。已有 G0–G7 门；5 步 chunk、相对目标、IBVS/PBVS 都有离线/仿真路径。
- **所需资源**：3–4 人周 + 1 GPU 周；腕部/头部标定；目标库 <1GB。
- **落地步骤**：① 用已知腕部内参做 IBVS 验证；② 从成功演示检索「受器→夹爪」相对目标；③ 30 步 plan / 5 步执行；④ 在 3–5 个终局 50 分任务做 A/B；⑤ 扫 chunk 3/5/8 与 RTT。
- **风险**：远程 RTT、透明/反光物体、目标检索 mismatch、伺服压过 VLA 语义意图。
- **状态**：保留，执行层主投。

### P4 · PIVOT-REACH：只动 height/waist，不动 base（新增，中优先级）

- **动机**：官方 human 注释会移动物体/底座；某些任务高度较低（ArrangeTestTubes 0.689、PaperCupStacking 0.694、Unlock 0.717）。利用 pivot/height/waist 可以扩大可达范围、减少臂展极限，但数据里没有 base 平移。
- **与现有方案差异**：明确反对「移动底盘策略」。只做 `pivot` 的 height/waist 维度和安全包络；base `vx/vy/angle_z` 恒零；不建 SLAM/导航/里程计。
- **技术可行性**：中。`action.pivot` 存在且数据有 height 变化；但 `pivot_3/4/5` 语义未定义，必须先单任务验证。
- **所需资源**：1 人周；无需新数据；用现有 episode 和 `example_env.py`。
- **落地步骤**：① 用 `example_env.py` 确认 pivot 7 维的接受范围；② 先在 PickOutBatteries/ArrangeTestTubes/StoreCups 上返回「零 base、固定/小幅 height」；③ 做高度 ±2 cm、waist ±0.05 rad 的安全限幅；④ 单任务 A/B：pivot on/off；⑤ 若 pivot 语义不匹配，立即回退全零。
- **风险**：pivot 语义不一致导致动作被拒/机器人不动；base 固定；human 真移动机器人时无 base 观测；高度调整引发碰撞。
- **状态**：新增，中优先级；G6 不过就剪枝。

### P5 · HUMAN-TWIN：用官方 human_1/human_4 注释做定向扰动与恢复（新增，中优先级）

- **动机**：human 泛化占 20%（2/10）；官方每个任务都给了 human_1/human_4 的具体扰动；当前模型只在成功演示上训练，没有恢复数据。
- **与现有方案差异**：不是泛泛的 domain randomization；而是把官方注释变成 32×2 的脚本化扰动（移动物体、拿走物体、撤销动作、把物体放回起点），做配对恢复评测；恢复可由确定性伺服 + 重规划完成，也可用 LoRA 在合成数据上适配。
- **技术可行性**：中。部分扰动可在仿真/回放中实现；真机只能用单任务通道少量验证；不需要新采集大规模数据。
- **所需资源**：1–2 人周；官方 IsaacLab/MuJoCo 或离线回放；单任务通道。
- **落地步骤**：① 解析 32 个任务的 human notes；② 建 64 个扰动脚本/检查表；③ 离线/仿真注入，测检测延迟与恢复率；④ 用 rubric 指定「恢复到哪一步」；⑤ 只把有效的恢复策略接进 CHUNK-SERVO 状态机。
- **风险**：sim-to-real gap；human 注释不完整；安全（停/撤/重抓）；恢复动作可能被评分判为失败。
- **状态**：新增，中优先级；与 P1/P3 合并，不单独烧正式提交。

### P6 · DG-KEYFRAME：从 33k 成功演示检索相对目标（保留，升级）

- **动机**：位置/人为干扰下，绝对动作会错；相对「受器→夹爪」位姿可以跟着目标移动。
- **与现有方案差异**：保留第 12 轮做法；本轮用腕部已知内参改 IBVS，用 RUBRIC-GRAPH 的终局步骤选关键帧，减少目标库噪声。
- **技术可行性**：高。33k episodes，A 档约 19k；每 episode 1–2 个关键帧；目标库 <1GB。
- **所需资源**：1 人周；CPU；存储 <1GB。
- **落地步骤**：① 按 rubric 终局步骤选关键帧；② 估计 `T_target_ee*`；③ 存腕部目标图/描述子；④ 检索 + top-k 重打分；⑤ 置信度低回退 VLA。
- **风险**：透明/反光/变形；检索 mismatch；相机外参漂移。
- **状态**：保留；CHUNK-SERVO 的子模块。

## 4. 方法：RUBRIC-LORA

### 4.1 RUBRIC-GRAPH：从 94 个步骤到采样权重

对任务 `t`，评分步骤 `k=1..K_t`，权重 `w_{t,k}`，`Σ_k w_{t,k}=100`。对成功 episode 做相位分割，得到帧到步骤的弱标签 `z_{i,k}`。采样权重：

```text
P(frame i of task t) ∝ w_{t, z_i} * (1 + β * 1[z_i = K_t]) * task_priority_t
```

- `β` 先取 1.0–2.0，只对终局步骤加权，不要只采终局；
- `task_priority_t` 由竞赛策略给（见 §5）；
- 验证指标用 **rubric-weighted MSE/MAE**：

```text
L_rubric = Σ_t Σ_k w_{t,k} * MSE_k / Σ_t Σ_k w_{t,k}
```

这比均匀 MSE 更贴近「高权重终局步骤不能错」的目标。

### 4.2 LORA-PORTFOLIO：6–8 个候选，合并成一个

候选轴（先做 6 个，不要一次铺 8 个）：

| 轴 | 数据/配置 | 目的 |
|---|---|---|
| A0 | 32 任务均衡 | 基线，防遗忘 |
| A1 | Hard-8 过采样 | 提升难任务 |
| A2 | 终局 50 分任务过采样 | 提升 success 敏感的终局 |
| A3 | human_1/human_4 扰动增强 | 提升 20% human 轴 |
| A4 | 背景/干扰物/未见物品增强 | 提升 40% 视觉泛化轴 |
| A5 | joint vs ee / chunk 5 vs 30 | 选控制空间与执行粒度 |
| A6 | action-head LoRA vs VLM+action LoRA | 选容量分配 |

训练配置建议：

- action head：`r ∈ {16, 32, 64}`，`alpha = 2r`，dropout 0.05；先只训 attention，若欠拟合再加 FFN/AdaLN/proj_out；
- VLM：`r ∈ {8, 16}`，只训 q/k/v/o；只在 A6 开；
- 10K–20K steps；batch 1 + grad accumulation 8；lr 1e-4；cosine；24GB；
- 每个 adapter 保存 adapter-only；训练日志记录数据轴、rank、chunk、控制空间。

选择：

1. 离线 held-out（按 session/物体/背景分组）看 `L_rubric`，不要只看均匀 MSE；
2. 3–5 个单任务通道看 success + step score（这是唯一的官方密集信号）；
3. 选 top-3，做 TIES/DARE 合并；
4. 合并模型在全部 32 任务做离线回归；若比最佳单 adapter 退化 >2pp，回退到单个多任务 LoRA；
5. 最终只提交一个 checkpoint。

合并（TIES 简化版）：

```text
for each parameter p:
    deltas = [adapter_i[p] for i in topk_adapters]
    mask_i = topk(|delta_i|, keep=0.2)
    sign_p = sign(Σ_i delta_i * mask_i)
    agree_i = (sign(delta_i) == sign_p) * mask_i
    merged[p] = Σ_i delta_i * agree_i / max(Σ_i agree_i, 1)
final = base[p] + merged[p]
```

DARE 可作为替代：随机丢弃 60–90% 的 delta，再按 1/(1-p) 缩放。两种都先在离线验证，不要直接上真机。

### 4.3 CHUNK-SERVO：分数感知触发

不是每个 chunk 都做伺服；只在以下任一条件启用：

- 当前 rubric 阶段是终局高权重步骤（`w ≥ 40`）；
- 视觉残差/编辑检测超过阈值；
- 夹爪接近受器（`d_t < d_c`）。

其他时候保持 VLA 开环，省 RTT 和算力。

```text
plan = VLA(obs)                      # 30 步
for each 5-step block:
    if rubric_terminal or residual > θ:
        delta = servo(obs, goal)     # IBVS/PBVS，限幅 1cm/0.05rad
    else:
        delta = 0
    a = compose(plan[i:i+5], delta)
    return a
```

腕部内参已知，IBVS 可以直接用；相对目标来自 DG-KEYFRAME；目标不可见时回退 VLA/PBVS。

### 4.4 PIVOT-REACH：零 base，安全高度

```text
pivot = [0, 0, 0, 0, 0, 0, height_cmd]
height_cmd = clip(height_obs + Δh, 0.68, 0.75)   # 先保守
```

- 不输出 base `vx/vy/angle_z`；
- 不改 `pivot_3/4/5`，直到单任务通道验证语义；
- 高度每次最多 ±2 cm，waist 每次最多 ±0.05 rad；
- 只在低处/高处任务启用；其他任务固定 0.74；
- 若动作被拒或机器人不动，立即回退全零 pivot。

### 4.5 HUMAN-TWIN：检测 → 停 → 重定位 → 按 rubric 恢复

```text
if edit_score > θ for K frames:
    hold
    re-localize target with head stereo / wrist target image
    if target visible:
        resume servo at current rubric step
    else:
        VLA re-plan with new image + language
    if retries > max: fail gracefully
```

human 轴只占 20%，但它是「相对目标 + 重定位」最直接的检验场。

## 5. 竞赛策略：用 rubric 做投资组合

### 5.1 算术

- 总分 `S = (1/32) Σ_t p_t`，`p_t` 是任务 t 的 10 次平均成功率；
- 10 次/task，`p≈0.25` 时单任务 SE ≈ 0.137；32 任务平均 SE ≈ 0.024；
- human 轴 = 2/10 = 20%；human +10pp → 全局 +2pp；
- 10 个终局 50 分任务各 +10pp → `10/32×10 = +3.1pp`；
- 19 个 A 档任务各 +10pp → `19/32×10 = +5.9pp`；但不要把 19 个一次铺开。

### 5.2 任务优先级

```text
priority_t = (terminal_weight_t / 50) * (step_score_t / 100) * (1 - success_t) / cost_t
```

- `terminal_weight_t`：终局权重（50/40/25/20）；
- `step_score_t`：单任务通道/离线进度（高 = near-miss，值得救）；
- `success_t`：当前成功率（低 = 有空间）；
- `cost_t`：目标库/标定/评测成本。

先做 5 个代表任务：PlugInEthernet（终局 40、插入）、HangCup（终局 50、挂）、ZipUp（终局 50、拉链）、StackBowls（终局 40、叠）、FoldTowel（5×20、防回归）。通过后再扩到 10 个终局 50 分任务。

### 5.3 单任务通道协议

- 每任务 5 次 A/B（servo off/on 或 LoRA A/B）；
- 同一初始条件，尽量配对；
- 记录 success、step score、耗时、p99 延迟、恢复次数；
- 通过：≥3/5 任务 +10pp；FoldTowel 不回归 >5pp；
- 统计：配对差值 + bootstrap 95% CI；5 次只能看方向，不能看显著性；
- 不过门不烧正式 320 trials。

### 5.4 提交节奏

1. W0：API adapter + 官方 WLA 基线，单任务通道跑通 1 个任务；
2. W1：若允许多次提交，先交安全基线，锁「更早提交」tie-break；
3. W2–W3：RUBRIC-GRAPH 解析/对齐；LORA-PORTFOLIO 训练 6 个 adapter；
4. W4：离线筛选 + 3–5 个单任务 A/B；TIES/DARE 合并；
5. W5：CHUNK-SERVO + PIVOT-REACH 集成；chunk/gain 扫描；
6. W6：32×10 干跑；最终提交；保留回滚开关。

若只允许一次提交：跳过 W1，W5 后再交；不要用正式评测做未验证的 A/B。

| G3 | 合并是否不伤？ | 合并模型相对最佳单 adapter 退化 ≤2pp | 用单个多任务 LoRA；不合并 |
| G4 | 真机单任务是否涨点？ | ≥3/5 任务 +10pp；FoldTowel 不回归 >5pp | 不提交 RUBRIC-LORA 版本 |
| G5 | human 恢复是否有效？ | 检测 ≤200ms；离线/仿真恢复 ≥50% | 只做离线分析；不上线触发 |
| G6 | pivot 是否可用？ | 不拒动作；高度/waist 安全；base 恒零 | 全零 pivot；剪枝 PIVOT-REACH |
| G7 | 32 任务干跑是否稳定？ | N 端口隔离、reset 干净、内存不涨、p99 ≤150ms | 回退基线 |
| G8 | 消融是否支持因果？ | rubric > 均匀；合并 ≥ 单 adapter；5 步 > 30 步；伺服 > 无伺服 | 保留有效部分，砍掉无效部分 |

## 8. 一句话押注

**最值得押注的是 RUBRIC-LORA：用官方 94 个评分步骤做数据加权和任务组合，用官方 LoRA 在单卡上训练 6–8 个候选适配器并 TIES/DARE 合并成一个提交模型，再用 CHUNK-SERVO 的 5 步闭环补最后 3 厘米；移动底盘不投，pivot/height 只做可达性。**

# 第 13 轮产物 · RUBRIC-LORA 技术报告

> 检索/复核日期：**2026-11-02（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「RUBRIC-LORA」的工程化产物；不替换第 12 轮 CHUNK-SERVO，而是给它加上 **官方 rubric 监督层** 和 **LoRA 组合实验层**，并修正「腕部无内参」「移动操作」两个事实/方向问题。

## 0. 结论与边界

### 0.1 一句话结论

官方 32 个任务不是 32 个 0/1，而是 **32×100 分、94 个带权评分步骤**；官方 UnifoLM-WLA 已开源 LoRA，公开 UniBot LoRA 也已在单张 4090 上完成 32 任务全量适配并合并成单个 checkpoint。因此本轮的核心不是「再训一个更大的 VLA」，而是：

> **用 rubric 决定练什么/先测什么，用 LoRA 在单卡上并行试 6–8 个方案并合并成一个提交模型，用 CHUNK-SERVO 的 5 步闭环补最后 3 厘米，用 PIVOT-REACH 只做 height/waist 可达性而不造移动底盘。**

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、任务 `info.json` 直接核实 | 32 任务/94 步/3200 分；33,276 eps；腕部内参；LoRA 配置；API 字段 |

### 0.3 本轮不做什么

- 不造移动底盘/导航/SLAM：数据里 base 平移为零。
- 不从零训 VLA/World Model：官方 WLA 6B 已开源。
- 不做完整 sim-to-real 策略训练：数字孪生只做控制器/扰动风洞。

### 1.4 API 与 pivot/base 字段（A+B）

提交模板 README（2026-11-02）给出：

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640** |
| 本体 | 双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str` |
| 动作空间 | `control_space` 仅 `"joint"` 或 `"ee"`，二者互斥 |
| 共享动作 | `action.left_gripper [1]`、`action.right_gripper [1]`、`action.pivot [7]` |
| EE 动作 | `action.left_ee_pose_gripper_base [6]`、`action.right_ee_pose_gripper_base [6]`（绝对目标位姿，xyz+rpy，base 系） |
| chunk | `action_chunk_size` ≥1，固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action` |
| token | `metadata.token` 握手校验一次；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile** |
| 监控 | 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分 |

#### 抽样：base 平移几乎为零（B）

对 32 个数据集各取前 100 帧，计算 `action.base_command` 的 `vx/vy/angle_z`：

```text
max |vx|, |vy|, |angle_z| across 32×100 frames < 2.5e-12
height range: 0.6890 – 0.7400 m
pivot_4: 0.0 or 0.15 (task-dependent)
pivot_3, pivot_5: 0.0
```

**结论**：

- 当前 benchmark 的 base 是固定的；训练数据没有 base 平移/转向。
- 「移动操作」在数据里主要表现为 **height/waist/躯干** 的调整，而不是底盘移动。
- `pivot_3/4/5` 的语义官方未定义，不能猜；先用 `example_env.py` + 单任务通道验证。
- 不要造移动底盘/导航/SLAM；把工程投到 PIVOT-REACH（height/waist）和视觉恢复。

## 2. 问题形式化

### 2.1 评分与排名

32 个任务，每任务 100 分，总分 3200；每任务 10 次 trial。定义：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

排名是字典序：

```text
rank key = (S, average_step_score, -submission_time)
```

即成功率优先，步骤分是 tie-break。步骤分不能替代成功率，但可以作为**密集训练信号**和**模型选择信号**。

320 trials 下，若 `p≈0.25`：

```math
\mathrm{SE}(S)\approx \sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

单任务 10 次 trial 的 SE：

```math
\mathrm{SE}(p_t)=\sqrt{\frac{p_t(1-p_t)}{10}}\approx 0.137\quad(p_t=0.25).
```

所以：

- 单任务 +10pp 在 10 次 trial 下可能是噪声；必须配对 A/B 或重复；
- 32 任务平均的 SE 约 2.4pp；不要声称 +1–2pp 是结论；
- human 轴 = 2/10 = 20%；human +10pp → 全局 +2pp；
- 10 个终局 50 分任务各 +10pp → `10/32×10 = +3.1pp`；
- 19 个 A 档任务各 +10pp → `19/32×10 = +5.9pp`，但一次铺 19 个成本太高。

### 2.2 Rubric 图

对任务 `t`，评分步骤 `k=1..K_t`，权重 `w_{t,k}`，`Σ_k w_{t,k}=100`。把步骤建成有向序列/弱 DAG：

```math
G_t = (V_t, E_t),\quad V_t=\{s_{t,1},...,s_{t,K_t}\},\quad
E_t=\{(s_{t,k},s_{t,k+1})\}.
```

对成功 episode `e`，用相位分割/时间对齐得到帧 `i` 的步骤标签 `z_{e,i}∈{1..K_t}`。定义密集进度：

```math
\rho_{t,e}(i)=\frac{1}{100}\sum_{k=1}^{K_t} w_{t,k}\,\mathbf{1}[k\le z_{e,i}].
```

用途：

1. **数据加权**：高权重步骤/终局步骤多采；
2. **验证指标**：rubric-weighted MSE；
3. **伺服触发**：只在终局高权重步骤或残差大时伺服；
4. **竞赛组合**：终局权重 × near-miss / cost。

### 2.3 采样权重

```math
P(i\mid t)\ \propto\ w_{t,z_{e,i}}\cdot
\left(1+\beta\,\mathbf{1}[z_{e,i}=K_t]\right)\cdot
\pi_t,
```

其中 `β∈[1,2]`，`π_t` 是任务优先级。不要只采终局；前置步骤缺失会让终局永远到不了。

### 2.4 LoRA 选择目标

对候选 adapter `a`，定义 rubric-weighted 验证误差：

```math
L_{\mathrm{rubric}}(a)=
\frac{\sum_{t}\sum_{k} w_{t,k}\,\mathrm{MSE}_{t,k}(a)}
{\sum_{t}\sum_{k} w_{t,k}}.
```

但 `L_rubric` 仍只是开环动作误差；最终选择必须加单任务通道的真实 success/step score：

```math
\mathrm{score}(a)=\alpha\,\mathrm{success}(a)+\beta\,\mathrm{step}(a)-\gamma\,\mathrm{latency}(a).
```

选择 top-3 做合并；合并后用全任务回归和单任务通道复核。

### 2.5 执行/延迟模型

设：

- `f_c`：evaluator 控制频率（假设 30Hz）；
- `H_c`：提交的 `action_chunk_size`；
- `τ`：网络 RTT + 推理 + 图像传输的等效延迟；
- `T_fb`：从世界变化到策略看到变化的反馈周期。

```math
T_{\mathrm{fb}}\approx \frac{H_c}{f_c}+\tau.
```

| 场景 | `H_c` | `f_c` | `τ` | `T_fb` | 评价 |
|---|---:|---:|---:|---:|---|
| 官方 WLA 默认 | 30 | 30 | 50ms | **1050ms** | 接触段基本开环 |
| 公开 LoRA | 50 | 30 | 50ms | **1717ms** | 更差；只适合慢速搬运 |
| 本方案保守 | 5 | 30 | 50ms | **217ms** | 可做 1–2 次接触修正 |
| 本方案高延迟 | 5 | 30 | 150ms | **317ms** | 增益降档 |
| 低控制频率 | 5 | 10 | 50ms | **550ms** | 改 `H_c=3` 或只做 PBVS |

**结论**：chunk size 不是推理参数，是控制参数；必须按实测 `f_c` 和 `τ` 选。

### 2.6 PIVOT 安全包络

```math
\begin{aligned}
v_x &= v_y = \omega_z = 0,\\
h_{k+1} &= \mathrm{clip}(h_k+\Delta h,\ 0.68,\ 0.75),\\
|\Delta h|&\le 0.02\ \mathrm{m},\\
|\Delta \psi_{\mathrm{waist}}|&\le 0.05\ \mathrm{rad}.
\end{aligned}
```

`pivot_3/4/5` 先固定 0；只有单任务通道确认语义后才放开。

映射：

1. `left_ee_abs = compose(T_base_ee_left_current, exp(left_ee_rel))`；再转 xyz+rpy。
2. `right_ee_abs` 同理。
3. gripper 直通；校验 0–1 方向。
4. `pivot = [0, 0, 0, 0, 0, 0, height]`；`height` 从 WLA `height`/`waist` 映射；`pivot_3/4/5` 先 0。
5. 腿部/灵巧手在 `ee` 模式不直接下发。

**关键细节**：

- WLA 的每个未来动作是「相对 plan-time 当前 EE」；必须先把整个 30 步 compose 成 base 系绝对目标，再按 5 步切片。否则第 6–30 步会以错误锚点解释。
- WLA EE 是 pelvis base，Dex1 偏移 `[0.105, 0, 0]`（GitHub issue #16）；挑战赛的 `*_ee_pose_gripper_base` 需重投影验证，误差 ≤1cm/2°。
- 公开 LoRA 使用 joint 控制；如果走 joint，adapter 需要 `action.left_arm/right_arm`，不能混用 EE。

### 3.4 `get_action` 伪代码（分数感知触发）

```python
class RubricLoraPolicy:
    def get_action(self, obs):
        self._tick(obs)
        self._maybe_request_plan(obs)

        if self.plan is None:
            self.plan = self.vla.predict(obs)   # cold start; timeout -> hold
            self.plan_idx = 0

        a_ff = self.plan[self.plan_idx : self.plan_idx + self.H_c]

        use_servo = (
            self.rubric.is_terminal(self.phase, w_min=40)
            or self.residual > self.theta_residual
            or self.near_contact()
        )
        if self.mode == "SERVO" and self.goal is not None and use_servo:
            delta = self.servo.compute(obs, self.goal)   # 6D, clipped
            a_cmd = compose_relative(a_ff, delta)
        else:
            a_cmd = a_ff

        self.plan_idx += self.H_c
        if self.plan_idx >= len(self.plan):
            self.plan = None
            self.plan_idx = 0

        return self.adapter.to_api(a_cmd, obs, self.token)
```

规则：

- VLA 永远不阻塞 `get_action`（除冷启动）；plan 过期就用旧 plan + 伺服。
- 每个 chunk 只做一次伺服；伺服失败不影响返回合法动作。
- 任何异常 → 返回上一组合法 chunk 或安全 hold；绝不返回 NaN/错误形状。
- `use_servo` 由 rubric 阶段/残差/接触距离共同决定；不是每个 chunk 都伺服。

```python
def safe_pivot(obs, proposed):
    # proposed: (T,7) from adapter
    out = proposed.copy()
    out[:, 0:3] = 0.0                       # no base translation/rotation
    out[:, 3:6] = 0.0                       # pivot_3/4/5 not validated
```

### 3.8 HUMAN-TWIN 状态机

```text
INIT ──first obs──▶ PLAN ──plan ready──▶ SERVO
  ▲                   ▲                    │
  │                   │                    ├─ terminal step ──▶ CONTACT
  │                   │                    │                     │
  │                   │                    │                     └─ done ──▶ DONE
  │                   │                    │
  │                   └── replan ◀── RECOVER ◀── edit_score > θ_e
  │                                      │
  └──────────────────────────────────────┘
任意状态 ──task success / max steps──▶ DONE
```

- `SERVO`：正常接近，PBVS 主导，IBVS 辅助。
- `CONTACT`：`d_t < d_c` 或 rubric 终局；法向缩幅/低通，切向保留。
- `RECOVER`：编辑检测触发；先停，再重定位；目标可见 → 更新 goal；不可见 → VLA 重规划。
- `DONE`：任务成功/最大步数；清理状态，等待 `reset()`。

### 4.3 合并算法

#### TIES（简化）

```python
def ties_merge(base, deltas, keep=0.2):
    merged = {}
    for k in base:
        stack = torch.stack([d[k].float() for d in deltas])  # (M, ...)
        flat = stack.flatten(1)
        kth = max(1, int(keep * flat.size(1)))
        thresh = flat.abs().topk(kth, dim=1).values[:, -1:]
        mask = flat.abs() >= thresh
        sign = torch.sign((flat * mask).sum(dim=0))
        agree = (torch.sign(flat) == sign) & mask
        num = (flat * agree).sum(dim=0)
        den = agree.sum(dim=0).clamp(min=1)
        merged[k] = (base[k].float() + (num / den).view_as(base[k])).to(base[k].dtype)
    return merged
```

#### DARE（替代）

```text
for each delta:
    mask ~ Bernoulli(keep_prob)
    delta = delta * mask / keep_prob
merged = base + Σ delta
```

`keep_prob` 取 0.1–0.4；先在离线验证，不要直接上真机。

## 5. CHUNK-SERVO 集成（压缩版）

### 5.1 双频执行

```text
VLA:   每 30 步（1s）产出一个 30 步 plan；后台线程；不阻塞 get_action
Servo: 每 5 步（167ms）用最新腕部/头部图修正一次；返回 5 步 chunk
API:   metadata.action_chunk_size = 5；evaluator 执行 5 步后再次调用
```

### 5.2 腕部内参与 IBVS

腕部 `color` 内参已知（§1.3），IBVS 交互矩阵可直接用：

```math
L_s^{px} =
\begin{bmatrix}
-\dfrac{f_x}{Z} & 0 & \dfrac{u-c_x}{Z} &
\dfrac{(u-c_x)(v-c_y)}{f_y} &
-\dfrac{f_x^2+(u-c_x)^2}{f_x} &
\dfrac{(v-c_y)f_x}{f_y}\\[6pt]
0 & -\dfrac{f_y}{Z} & \dfrac{v-c_y}{Z} &
\dfrac{f_y^2+(v-c_y)^2}{f_y} &
-\dfrac{(u-c_x)(v-c_y)}{f_x} &
-\dfrac{(u-c_x)f_y}{f_x}
\end{bmatrix}
```

```math
\mathbf v_c = -\lambda\,L_s^{+}(\mathbf s-\mathbf s^*)
```

- 单点只有 2 个约束；用 ≥3 点/轮廓/线特征，或只控制任务相关子空间。
- `Z` 用头双目深度或先验；透明/反光 → 置信度低 → 回退 PBVS/VLA。
- 目标图 `I_wrist(k)` 来自 DG-KEYFRAME；特征用 ORB/轮廓/颜色块。

### 5.3 PBVS

```math
T_{err}=T_{ee}^{-1}T_{ee}^{d},\qquad
e=\begin{bmatrix}t_{err}\\ \log(R_{err})\end{bmatrix},\qquad
\mathbf v_c=-\lambda K e.
```

- `T_ee^d = T_base_target(t) · T_target_ee*`；
- `T_base_target` 用头双目 + 局部 ICP/几何；
- 远距离 >5cm 用 PBVS；近距离 <2cm 用 IBVS；中间置信度加权。

### 5.4 延迟稳定性

简化离散积分器：

```math
e_{k+1}=e_k-K H_c\,e_{k-d},\qquad d=\tau/(H_c/f_c).
```

- `d=0`：稳定域 `0<KH_c<2`；
- `d=1`：稳定域 `0<KH_c<1`；
- `d=2`：进一步缩小；必须降增益或加预测。

实践：

- 用 `τ` 测量值做 Smith 预测；
- `K_eff = K_0/(1+\tau/\tau_0)`，`τ_0=50ms`；
- 仿真扫 `τ∈{0,50,100,150}ms`；
- 若 `T_fb>300ms`，关闭 IBVS，只做 PBVS + VLA。

## 6. 竞赛策略

### 6.1 任务优先级

```math
\mathrm{priority}_t=
\frac{w_{\mathrm{terminal},t}}{50}\cdot
\frac{\mathrm{step}_t}{100}\cdot
(1-\mathrm{success}_t)\cdot
\frac{1}{\mathrm{cost}_t}.
```

- `w_terminal`：终局权重；
- `step_t`：单任务通道/离线进度（高 = near-miss）；
- `success_t`：当前成功率；
- `cost_t`：目标库/标定/评测成本。
