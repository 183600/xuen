# 第 8 轮 · SODT：把评分步骤做成可观测的孪生裁判

> 检索/复核日期：**2026-10-26（UTC）**。赛事身份不变：宇树科技 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「双足机器人」「专利布局」「数字孪生」。我先纠正上一轮两个会改变资源分配的事实，再把三个词钉到可执行的判断上。
>
> **纠正一（排名规则）**：官方手册明确，实时榜单按 32 个任务的**总平均成功率**排序；成功率相同才看总平均步骤分；再相同才看提交时间 [S1][S2]。上一轮把「终局步骤占 39.8%、放置类步骤占 59.7%」当成“步骤分是大头”的主要论据，这个算术必须降级：**终局步骤的第一价值是成功闸门，不是分项权重**；步骤分只在同分时救场。
>
> **纠正二（双足）**：32 个任务的演示数据里，G1 的 `action.pivot` 几乎恒定：`vx/vy/angle_z≈0`、`pivot_4≈0.15`、`height≈0.737 m`（中间三轴在数据集 card 中只叫 `pivot_3/4/5`，语义需调试槽确认）；双腿没有承担走位，腰部只有小幅运动 [S5][S6]。所以「双足走位/主动移动基座」是分布外动作，不应作为主押注；双足平台真正能用的是**固定站姿 + 头部立体视觉 + 小范围躯干几何**。
>
> **本轮主判断**：**不要造更大的 VLA，也不要造全物理孪生；造一个任务局部的对象级度量孪生（SODT, Step-Observable Digital Twin），把 32 个官方评分步骤变成可观测谓词，用它在推理时门控释放、验证落点、检测人为撤销并触发最小重试；学习侧仍只有一个 VLA checkpoint。** 专利上，这不是宇树“数字舞台/舞蹈/轨迹生成”的孪生，也不是 Figure 的“分层双足动作模型”，而是**只做裁判、不做控制的窄孪生**——恰好落在现有专利的空白处 [S11]–[S15]。
>
> **一句话押注**：用“步骤可观测的孪生裁判”把静默失败变成可重试的失败，先把成功率主键抬起来，步骤分只作为同分时的自然副产品。

## 0. 本轮先核实：七个事实

### 0.1 每个任务 10 次运行，5 类泛化各 2 次；成功率优先，180 秒硬超时

官方中英文手册（[S1][S2]）写明：

- 每个任务执行 **10 次独立运行**，每次采用不同泛化设定；10 次中包含 **5 类泛化，每类各 2 次**：位置、干扰物、桌面背景、未见物品、人为干扰。
- 因此总评测量是 **32 × 10 = 320 trials**；每一类泛化固定占 **64 trials / 20%**。
- 每个任务单次真机执行**最大 180 秒**，超时记为失败，并按执行情况计算步骤分。
- 榜单按 **32 任务总平均成功率**排序；成功率相同看总平均步骤分；再相同看提交日期。
- 只允许**一个模型**完成全部 32 任务；不限制模型架构（World Models、VLA 等都可以）；模型由选手自部署，官方通过远程 API 调用。
- 另有**不计分单任务测试通道**，可用于发布前的真机 A/B。

这条事实把优化目标钉死了：**先救 success，再谈 step score**。上一轮的“终局放置是闸门”仍然成立，但“放置占 60% 分数所以放置最重要”的说法要改成“放置是 32/32 任务的最后一道 success 闸门，因此它最重要”。

### 0.2 32 个任务的终局步骤全部是成功闸门；终局权重合计 1275/3200

32 个 `tasks_v2/<slug>/info.json` 的 `score_steps` 已公开（2026-10-24 抓全，2026-10-26 复核缓存）[S3][S4]：

- 满分统一 100；步骤数 2–5；难度 12 Easy / 12 Medium / 8 Hard。
- 32 个终局步骤合计 **1275/3200 = 39.8%** 的步骤权重；放置/插入/堆叠/闭合类步骤约 **1910/3200 = 59.7%**（按关键词粗分类）。
- 32 个终局步骤中 **28/32** 是放置/插入/堆叠/闭合类，另外 4 个是拔出/取出/翻转/倾倒（T05 拔网线、T11 挑电池、T12 翻金属环、T14 倒药）。
- 每条指令在数据集里有 **5 条英文复述**（32×5=160）[S7]；语言评测很可能在这 5 条里采样。
- 终局步骤是 success 的必要条件；步骤分是失败 episode 的部分分，也是同分时的次级键。

**诊断含义**：终局步骤是“钱丢得最集中”的地方，但它值钱主要是因为**它一失败，前面全白做**；不是因为那 40 分在排名公式里占 40%。所以任何“为了多拿部分分而增加终局失败风险”的策略都应该砍掉。

### 0.3 双足负结果：32 个任务的 base 几乎不动，双腿不是走位资产

我从 Hugging Face 的 32 个数据集 `meta/stats.json` 聚合了 `action.pivot`、`observation.state.waist_state_joint` 与 `action.base_command`（[S5][S6]）：

| 统计量（32 任务） | 结果 | 解释 |
|---|---|---|
| `pivot[0]` vx 均值 | 0.00000（min −1e−5, max 1e−5） | 前后不走 |
| `pivot[1]` vy 均值 | 0.00000（min −2e−5, max 1e−5） | 左右不走 |
| `pivot[2]` angle_z 均值 | 0.00003（max 1.2e−4） | 不转向 |
| `pivot[3]` 均值 | −0.00042（min −0.0134） | 中间轴，语义未文档化 |
| `pivot[4]` 均值 | 0.14987（min 0.1132, max 0.2141） | 中间轴，若为 pitch 则约 8.6° |
| `pivot[5]` 均值 | 0.0 | 中间轴，语义未文档化 |
| `pivot[6]` height 均值 | 0.73712（min 0.7273, max 0.7400） | 固定站高 |
| 腰部 pitch 标准差 | 0.0092–0.0929 | 只有小幅俯仰 |
| 腰部 yaw 标准差 | 0.0146–0.0747 | 只有小幅转腰 |

> 注：`meta/info.json` 的 `action.pivot.names` 只给 `vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height`；`pivot_3/4/5` 的语义未在数据卡文档化。上表“若为 pitch”是假设，站姿实验必须验证。`action.base_command` 的 4 维均值同样是 vx≈0、vy≈0、angle_z≈3e−5、height≈0.73712，与 pivot 一致。

**结论**：这不是“双足行走 + 双臂操作”的数据，而是**固定基座的双臂/躯干操作**数据。任何“走到物体旁/绕桌移动/用腿调整站位”的策略在演示分布外，评测也不会给演示里没有的走位能力发奖。双足灵感的正确落点是：

1. **固定站姿先验**：推理时不要照抄示例策略的“全零 pivot”；先验证 pivot 是绝对还是增量。如果是绝对，按任务取 pivot 均值（全局约 `[0,0,0,0,0.15,0,0.738]`）才更接近演示站姿（中间三轴语义待确认）；全零可能让机器人变成另一个姿态。不同任务站姿差异明显（如 T15 OrganizeTools 的 `pivot[4]≈0.214`、T23 StorePaddle≈0.113），不能一个值走天下。这是一个 1 天就能在调试槽验证的接口级收益。
2. **立体头 + 腕部相机做度量**：G1 头部有左右立体 RGB，数据集四路相机是 480×640；固定基座 + 已知站高 + 桌面平面，足以把像素提升到**厘米级粗米制**，不需要额外深度传感器。注意头部双目基线只有约 54.8mm，0.7m 处 1px 视差约 4.8cm，**精对齐必须靠腕部近距相机 + ICP/视觉伺服**，头部只负责桌面布局/粗定位。
3. **小范围躯干视角**：腰部在演示中只小幅运动；除非调试槽证明 pivot 的小角度安全，否则不要主动用 base 运动换视角，优先用腕部相机和立体头。

这条负结果的价值是**省掉 2–3 周的走位/移动基座试错**，把火力集中到“看得准 + 放得准 + 知道什么时候算成功”。

### 0.4 数据与接口：四路 RGB、30fps、约 33k episodes，服务端可维护状态

- 32 个任务约 **33k episodes / 169 小时**；HangCup 1,043 episodes / 194,564 帧；StackBowls 979 / 295,609 帧；30fps [S5][S6]。
- 观测：`head_stereo_left/right`、`wrist_left/right` 四路 RGB 480×640；双臂关节/EE 位姿、夹爪、`lower_body[15]`、`language` 单字符串 [S8]。
- 动作：`action.pivot[7]` + 左右臂（joint 或 ee 二选一）；`obs_delta_indices` 自定义观测堆叠，`image_resize` 自定义分辨率，`action_chunk_size` 自定义 chunk；`reset()` 每 episode 一次 [S8]。
- 官方通过远程 API 调用我们的服务，因此**孪生可以跑在我们自己的服务端**，跨 API 调用维护 episode 内状态；只要 `reset()` 清空即可，不需要额外接口。
- 180 秒/task 是硬预算；孪生应在 chunk 边界更新（例如每 16–30 个动作一次），而不是每帧跑重感知。

这决定了 SODT 的工程形态：**同一进程内的确定性状态机 + 轻量几何**，不是另一个大模型服务；延迟预算 100–200ms/chunk，VLA 仍是主要耗时。

### 0.7 数字孪生文献：训练期、重建期、评估期都有人做，推理期“步骤裁判”是空位

本轮核对的相关工作（[S16]–[S20]）：

- **TwinRL**（arXiv:2602.09023）：digital twin 驱动的 RL，用孪生扩展在线 RL 的探索空间——训练期。
- **SyncTwin**（arXiv:2601.09920）：VGGT 重建对象资产 + 点云分割跟踪，做 real-to-sim 同步与安全操作——重建/同步期。
- **ReVeal**（arXiv:2609.23910）：重建感知的 real-to-sim 评估，用 NVMF/APGF 评估重建保真度——评估期。
- **VPTwin**（arXiv:2609.33104）：real-sim-real 视频预测，用孪生锚定长时程预测——预测期。
- **ActiveScale**（arXiv:2609.18514）：主动感知的模型/数据/硬件扩展——感知期。

它们共同证明：**对象级、任务局部的孪生是可行且有用的**；但没有一篇把“官方评分步骤”变成推理时的成功谓词，并用它触发重试/恢复。我们的空位不是“再做一个孪生”，而是**把孪生从训练/评估工具变成在线裁判**。

## 1. 三个灵感词，各自钉到一个可执行判断

### 1.1 双足机器人：不是走位，是固定站姿下的立体几何

数据已经说明双腿没有走位（§0.3）。所以本轮不押：

- 不做行走/移动基座/绕桌走位；
- 不做全身 RL/步态；
- 不把 `lower_body[15]` 当成主要控制变量。

本轮押：

- **站姿先验**：用 32 任务统计出的固定 pivot 作为默认值，并在调试槽做 A/B（全零 vs 数据均值）。
- **立体度量**：用头部左右目 + 桌面平面 + 已知站高，恢复对象米制位姿；腕部相机补遮挡。
- **小范围视角**：只在调试槽确认安全后，用极小的 base pitch/yaw 调整视角；否则不动 base。
- **双足平台的真正优势**：站得高、看得远、双臂工作空间大、头部立体基线固定；这些正好服务桌面放置，而不是走位。

### 1.2 专利布局：把“控制侧孪生”让给宇树，把“裁判侧孪生”留给自己

专利地图（§0.6）给我们的不是“不能做”，而是“怎么做才不撞”：

1. **不做**：数字舞台/舞蹈/轨迹生成（CN120552084B）；分层 Beta/Alpha 双足动作模型（US12638859B2）；扩散策略 + 场景交互预测（CN120941414B）；孪生上 RL（WO2025193030A1）；泛泛的主动感知调度（US11839986B2）。
2. **做**：对象级状态估计 + 任务步骤谓词 + 释放门控 + 落点验证 + 外部编辑检测 + 最小重试。孪生**不输出运动轨迹/控制指令**，只输出“这一步是否真的完成/是否被撤销/是否值得重试”的判定；动作仍由单一 VLA 生成。
3. **防御性公开**：在模型卡/技术报告里公开谓词 DSL、步骤状态机、容器系放置迁移、外部编辑状态 diff 的实现细节，形成 prior art，降低被上游专利覆盖的风险。
4. **可专利点（若商业化）**：不是“数字孪生”本身，而是**“基于官方评分步骤图的对象级孪生裁判 + 释放后 settle 验证 + 外部编辑回滚”**的具体组合；先做 provisional/FTO，不把通用 VLA 或通用孪生写进权利要求。

### 1.3 数字孪生：窄、对象级、推理期、只裁判

本轮定义的 SODT 不是 Gazebo/Isaac 的全物理孪生，也不是训练期 RL 环境，而是：

- **窄**：只建当前任务相关的桌面、容器、目标对象、夹爪与支撑关系；不建整间房、不建全身动力学。
- **对象级**：每个对象有 id、6D pose、点云/包围体、支撑/接触关系、任务角色（target/container/tool/obstacle）。
- **同步**：每个 action chunk 后用四路 RGB + 双目 + proprio 更新；检测“没有机器人接触却动了”的外部编辑。
- **可问 what-if**：给定候选释放位姿，检查碰撞、间隙、支撑、稳定性；不预测长期视频。
- **只裁判**：输出 step status / confidence / evidence / retry target；不输出关节/EE 轨迹，不替代 VLA。
- **可校准**：用官方 demo 的最终状态和调试槽真机结果校准谓词阈值；所有阈值显式记录。

这比全物理孪生便宜、比纯 VLA 可解释、比学习型 success classifier 数据效率高；而且正好避开控制侧专利。

## 2. 主押注：SODT / Referee Twin

### 2.1 一句话系统

**一个 VLA 负责“怎么做”，一个对象级度量孪生负责“做到了没有、要不要重试”。**

```text
四路 RGB + 双目 + proprio
        │
        ▼
[感知适配] 立体深度 / 桌面平面 / 对象检测 / 6D pose / 夹爪状态
        │
        ▼
[对象图孪生] 对象 id · pose · 支撑 · 接触 · 任务角色 · 外部编辑标记
        │
        ▼
[步骤谓词引擎] 32 任务 score_steps → 几何/语义谓词 → achieved/failed/undone
        │
        ▼
[状态机] 当前步 · 进度 · 置信度 · 重试预算 · 180s 剩余
        │
        ├──► [VLA 策略] 单一 checkpoint，chunk 动作 + 步骤提示/目标位姿
        │
        ▼
[受控执行] 站姿先验 · 碰撞/安全 · 释放门控 · settle 等待 · 最小重试
        │
        ▼
[日志/回放] 谓词证据 · 失败定位 · 调试槽校准
```

### 2.2 为什么它打的是 success 主键

- 32/32 任务的 success 都要求终局步骤完成；终局失败会让前面所有步骤归零。
- 现有 VLA 多为 open-loop chunk：动作发完就结束，**不知道自己有没有真的放进去**；失败是“静默”的。
- 孪生把静默失败变成**可观测失败**：释放后等待 0.3–0.8s，重估对象位姿；若谓词不成立或对象仍在移动，触发一次最小重试（微调/重抓/换放置点）。
- 一次重试的收益可以粗略写成：`Δsuccess ≈ (1−p) × d × r`，其中 p 是基线终局成功率，d 是孪生检出率，r 是重试成功率。取 p=0.3、d=0.5、r=0.2，得到约 **+7pp**；取 d=0.7、r=0.3，得到约 **+14.7pp**。真实值会低得多，但方向明确：**先救 success，不碰 step score 的算术**。
- 320 trials 下，p=0.3 的二项标准误约 **2.56pp**；+5pp 约 2 个 SE，+3pp 边缘。因此目标定为 **+3–6pp success**，并在任务层做配对分析，而不是只看总数。

### 2.3 为什么它能跨五轴

| 泛化轴 | 普通 VLA 的弱点 | SODT 的作用 |
|---|---|---|
| 位置 | 目标偏移后释放点错 | 容器/目标系相对位姿迁移；孪生检查间隙/支撑 |
| 干扰物 | 误抓/碰撞 | 对象图区分 target/obstacle；碰撞检查 |
| 背景 | 视觉域偏移 | 立体几何 + 桌面平面，不依赖背景纹理 |
| 未见物品 | 语义/形状陌生 | 开放词表检测 + 点云/包围体；谓词用几何而非固定类别 |
| 人为干扰 | 完成后被移动/撤销 | 外部编辑 diff；步骤回滚 + 最小重做 |

关键点：**SODT 的“裁判”不依赖任务类别固定模板**；它依赖对象角色和几何关系。语言由 VLA 处理，孪生只处理“状态对不对”。

### 2.4 为什么它可行且合规

- **单一学习模型**：只有一个 VLA checkpoint；孪生是确定性代码 + 几何，不是第二个策略。感知优先用经典立体/ICP/平面拟合；若用开放词表检测器，作为固定感知工具披露，并准备“孪生-lite”回退（仅用 VLA 特征 + 颜色/深度/平面）。
- **不改训练数据**：主路径只用官方 32 任务数据；不假设合成/外部数据被允许（手册只读到 2.2，需邮件确认）[S1][S2]。
- **延迟**：孪生只在 chunk 边界跑（16–30 动作一次），100–200ms；VLA 仍是主要耗时；180s/task 足够 1–2 次重试。
- **工程**：服务端维护 episode 状态，`reset()` 清空；不需要官方额外接口；所有阈值可配置、可回放。

### 2.5 为什么它新、且专利上安全

- 数字孪生文献：训练期（TwinRL）、同步期（SyncTwin）、评估期（ReVeal）、预测期（VPTwin）、感知期（ActiveScale）都有人做；**推理期步骤裁判**是空位（§0.7）。
- VLA 文献：有 self-check/reflection，但少有“官方 score_steps → 对象级几何谓词 → 释放后 settle → 外部编辑回滚”的完整闭环；官方评分步骤是本题独有的脚手架。
- 专利：宇树的孪生专利是舞台/舞蹈/样条轨迹；Figure 是 Beta/Alpha 分层双足动作；宇树扩散专利是策略；DxR 是训练期 RL。**SODT 只输出判定，不输出轨迹/控制**，设计上避开权利要求 1 的核心步骤（§0.6）。

### 2.6 什么会证伪它

- 谓词在离线 200 条 episode 上 precision < 80%，或 release-gate 误判导致更多失败；
- 3 个高价值任务（T01/T10/T27）调试槽里，SODT 的终局 success 增益 < 3pp；
- 孪生延迟超过 chunk 预算，导致 VLA 动作频率下降 > 20%；
- 官方明确“单模型”不允许任何额外感知模型，且孪生-lite 的精度不够；
- 重试在 180s 内无法完成，或重试本身把已成功步骤弄坏。

只要出现前两条之一，就退回“VLA + 站姿先验 + 固定步骤提示”，不再主推 SODT。

## 4. 开放问题与风险

1. **手册只读到 2.2**：外部/合成数据、感知工具、单模型边界尚未完全核实。动作：邮件 `challenge_support@unitree.com`；默认只用官方数据 + 确定性几何；准备孪生-lite。
2. **官方 success checker 不公开**：我们的谓词是代理，不是官方判分器。动作：用调试槽 + 人工标注校准；只在高置信度时门控。
3. **pivot 语义（绝对/增量）未核实**：全零示例可能是对的，也可能是坑。动作：调试槽 A/B；这是第一周实验。
4. **榜单是占位**：不能把 29.7/39.0 当真实。动作：只当结构先验；报告里显式标注。
5. **透明/可变形/细长对象**：拉链、毛巾、注射器、透明杯的 6D pose 难。动作：谓词降级为关键点/affordance + VLA；不承诺全物理。
6. **重试预算**：180s 内可能只够 1 次；重试可能破坏已成功步骤。动作：状态机记录“可回滚点”，只重做当前步；超时前放弃。
7. **开源 VLA 预训练权重是否算外部数据**：手册只读到 2.2，未明确。动作：邮件确认；默认只用官方数据微调，并在模型卡披露底座来源。
8. **专利 FTO 是初步**：只读了权利要求 1 和摘要，不是法律意见；若底座是扩散式/分层式 VLA，需单独做 claim chart。动作：商业化前请律师复核；竞赛期以防御性公开为主。

## 5. 本轮结论

**第 8 轮的主线不是“再做一个更大的模型”，而是“让模型知道自己有没有成功”。** 双足数据告诉我们不要走位；专利地图告诉我们不要做控制侧孪生；数字孪生文献告诉我们对象级窄孪生可行。三者交汇成一个可执行系统：**SODT / Referee Twin**——用固定站姿的立体几何建对象图，把 32 个官方评分步骤变成可观测谓词，在释放后验证、在人为撤销后回滚、在失败时最小重试；学习侧只有一个 VLA。它先打 success 主键，step score 只是同分时的自然副产品。

**一句话押注**：**用“步骤可观测的孪生裁判”把静默失败变成可重试的失败；不造全物理孪生，不造更大 VLA，不走位。**

## 1. 事实核对（全部一手或官方全文；来源见 §15）

### 1.1 赛制：10 次/任务，5 类各 2 次，180s，成功率优先

官方中英文手册 [S1][S2] 的关键原文：

- “每个任务执行 10 次独立运行，每次运行采用不同的泛化设定。”
- “10 次运行中包含以下 5 种泛化类型，每种类型各出现 2 次：位置泛化、干扰物泛化、桌面背景泛化、未见物品泛化、人为干扰泛化。”
- “每个任务单次真机执行最大允许执行时间为 180 秒，超时记为失败。”
- “实时榜单按 32 个任务的总平均成功率进行排序，成功率相同时按总平均步骤分排序，若仍相同，则提交日期较早的模型排序靠前。”
- “比赛仅设置通才模型赛道，非单模型 + 全任务的测试结果不会纳入排名系统。”
- “不限制模型架构（World Models、VLAs 等都可以）。”

**推论**：

1. 总 trials = 32×10 = **320**；每类泛化 = 32×2 = **64 trials / 20%**。
2. 优化第一目标是 **success**；step score 是 tie-break，不是 60% 权重。
3. 单模型是硬约束；任何“第二个策略模型”都有合规风险。SODT 必须是确定性代码/几何，不能是 task-specific policy。
4. 180s 是重试预算的上界；不是每次都能重试，状态机必须记录剩余时间。

### 1.2 评分步骤：终局是 32/32 的 success 闸门

32 个 `tasks_v2/<slug>/info.json` 的 `score_steps`（2026-10-24 抓全，2026-10-26 复核缓存）[S3][S4]：

- 满分 100；步骤数 2–5；难度 12 Easy / 12 Medium / 8 Hard。
- 终局步骤权重合计 **1275/3200 = 39.8%**；放置/插入/堆叠/闭合类步骤约 **1910/3200 = 59.7%**（按关键词粗分类）。
- 32 个终局步骤中 **28 个是放置/插入/堆叠/闭合类**；4 个是拔出/取出/翻转/倾倒（T05/T11/T12/T14）。
- 每条指令有 **5 条英文复述**（32×5=160）[S7]。

**正确用法**：

- 终局步骤是 success 的必要条件；它失败时前面步骤的分数只是部分分。
- 步骤分用于**诊断失败发生在哪一步**，以及同分时的次级排名；不要为了部分分增加终局失败风险。
- 终局权重 39.8% 是“失败集中度”的代理，不是排名公式的 39.8%。

**代表性终局步骤**（原文见 [S3][S4]）：

| 任务 | 终局步骤 | 权重 | 谓词化难点 |
|---|---|---:|---|
| T01 HangCup | Hang it on the marked spot on the rack | 50 | 杯柄/挂钩接触、杯身竖直、稳定 |
| T07 PlacePhotoFrame | Straighten the photo frame | 40 | 支架角度、相框直立、支撑 |
| T10 PlugCharger | Plug it into the power strip | 40 | 插头-插座对齐、插入深度、间隙 |
| T14 PourOutMedicine | Pour out the medicine | 50 | 瓶盖打开、药片出瓶、目标容器 |
| T19 ZipUp | Zip up the pouch | 50 | 拉链行程、拉头位置、闭合 |
| T27 StackBowls | Stack bowl 3 onto bowl 2 | 40 | 堆叠中心、互穿、稳定 |

### 1.3 数据与接口：四路 RGB、30fps、约 33k episodes

- 32 个任务约 **33k episodes / 169 小时**；HangCup 1,043 / 194,564 帧；StackBowls 979 / 295,609 帧；30fps [S5][S6]。
- 观测：`head_stereo_left/right`、`wrist_left/right` 四路 480×640；`observation.state.lower_body[15]`；`language` 单字符串；左右臂关节/EE 位姿；夹爪 [S8]。
- 动作：`action.pivot[7]` + 左右臂（joint 或 ee 二选一）；`obs_delta_indices`、`image_resize`、`action_chunk_size` 自定义；`reset()` 每 episode 一次 [S8]。
- 官方远程调用我们的服务：**孪生可以跑在服务端，跨 API 调用维护状态**；不需要新增官方接口。
- 数据集里 `action.pivot` 的名字是 “Lower-body / pivot target”；其绝对/增量语义未在 README 中明确，需调试槽 A/B（§2.3）。

**结论**：G1 在本赛事中是**固定基座的双臂/躯干操作平台**。演示没有走位，评测也没有给走位发奖。任何“走到物体旁/绕桌/用腿调整站位”的主押注都是 OOD。

**可利用的**：

- 固定站高 + 头部立体基线 + 桌面平面 → 稳定的米制尺度。
- 腕部相机补遮挡；头部双目补全局几何。
- 腰部小幅运动 → 被动视角变化，可作为多视角融合，但不要主动依赖。

**不要做的**：

- 行走/步态/全身 RL；
- 用 `lower_body[15]` 作为主要控制变量；
- 把 `action.pivot` 的大范围运动当成“移动基座”；
- 照抄示例策略的全零 pivot 而不验证语义。

## 2. 双足分析：为什么不做走位，做什么

### 2.1 为什么不做走位

- 演示中 base 平移/转向几乎为 0（§1.4）；走位是 OOD。
- 评测的 32 个任务都是桌面操作；任务描述没有“走到另一个桌子”的要求。
- 走位会引入平衡、碰撞、定位误差，且 180s 预算会被移动吃掉。
- 双足行走的专利/论文/工程都很拥挤，竞赛不奖励“走得像人”，只奖励“任务成功”。

### 2.2 做什么

1. **固定站姿先验**：默认用**每个任务**的 pivot 均值（全局约 `[0,0,0,0,0.15,0,0.738]`；中间三轴语义待确认），而不是全零；先验证绝对/增量。T15 OrganizeTools 的 `pivot[4]≈0.214`、T23 StorePaddle≈0.113，说明不能一个值走天下。
2. **立体度量锚**：头部双目 + 桌面平面 + 站高，恢复对象米制位姿；腕部相机补局部遮挡。
3. **被动多视角**：利用左右目和双腕四个视角，不主动移动 base；如果调试槽证明小角度 pivot 安全，再做 ±2° 内的视角微调。头部双目基线约 54.8mm、f≈186px；0.7m 处 1px 视差约 4.8cm，0.5m 处约 2.4cm——头部只做桌面布局/粗定位，插头级精对齐用腕部近距相机 + ICP/视觉伺服。
4. **腰部只读**：`lower_body[15]` 作为姿态/碰撞上下文，不作为主控制量。

### 2.3 站姿先验实验（第一周，1 天）

**目的**：确认 `action.pivot` 是绝对目标还是增量，以及全零是否会让机器人偏离演示站姿。

**设计**：

- 在单任务调试通道选 T01（HangCup）或 T10（PlugCharger），各 10 次。
- A 组：示例策略的全零 pivot；B 组：数据均值 `[0,0,0,0,0.15,0,0.738]`；C 组：只改 height=0.738，其余零。
- 记录：base 高度、pitch/roll、站立稳定性、抓取成功率、终局成功率、是否触发保护。
- 判定：如果 B 组显著更稳/更高，采用 B；如果 A/B 无差异，说明 pivot 是增量或评测有默认偏移，保持示例语义；如果 C 组最好，只修 height。

**价值**：这是一个 1 天、低风险、可能立刻收益的接口级实验；也是“双足灵感”最务实的落点。

## 4. 文献定位：我们不是又一个孪生，而是“裁判”

### 4.1 与五篇工作的差异

| 维度 | TwinRL | SyncTwin | ReVeal | VPTwin | ActiveScale | **SODT（本报告）** |
|---|---|---|---|---|---|---|
| 阶段 | 训练 | 重建/同步 | 评估 | 预测 | 感知 | **推理/执行** |
| 是否训练 | 是 | 否 | 否 | 是 | 是 | **否** |
| 是否全场景 | 是 | 是 | 是 | 是 | 是 | **任务局部** |
| 是否输出动作 | 是 | 否 | 否 | 规划 | 是 | **否（只裁判）** |
| 是否用官方步骤 | 否 | 否 | 否 | 否 | 否 | **是（32 任务 score_steps）** |
| 是否处理人为撤销 | 否 | 部分 | 否 | 否 | 否 | **是（外部编辑 diff）** |

### 4.2 我们的三个新意

1. **步骤可观测**：官方 `score_steps` 是公开的、任务无关的评分图；把它变成对象级谓词，而不是让 VLA 自己“感觉”完成。
2. **裁判不控制**：孪生只判定/触发重试，不生成动作；这既降低专利风险，也避免“第二模型”合规问题。
3. **释放后验证**：终局放置的失败很多是“放了但没放稳/没插进去”；释放后 0.3–0.8s 的 settle 重估是最高杠杆的一步。

| 谓词 | 语义 | 证据 | 典型任务 |
|---|---|---|---|
| `grasped(obj, gripper)` | 夹爪闭合且对象随动 | 夹爪开度 + 对象位移 | 所有抓取 |
| `on(obj, support)` | 对象在支撑面上 | 平面距离 + 法向 | 放置 |
| `in(obj, container)` | 对象在容器内 | 容器包围体 + 内部点 | 装袋/装箱 |
| `inserted(plug, socket)` | 插入到位 | 轴向对齐 + 深度 + 间隙 | T10/T26 |
| `closed(lid, angle)` | 闭合 | 铰链角/缝隙 | T09/T17 |
| `zipped(zip, progress)` | 拉链闭合 | 拉头位置/行程 | T18/T19 |
| `upright(obj)` | 直立 | 主轴与重力夹角 | T07/T08 |
| `stable(obj, t)` | 稳定 | 0.3–0.8s 位姿漂移 < 阈值 | 所有终局 |
| `clear(path)` | 路径无碰 | 碰撞体/点云 | 放置/插入 |
| `edited(obj, delta)` | 外部编辑 | 无接触位移/撤销 | human 轴 |

> T05/T11/T12/T14 的终局不是放置：分别用 `removed(cable, port)`、`removed(battery, slot)`、`flipped(ring)`、`poured(bottle, target)` 等任务特定谓词扩展；DSL 允许注册新谓词，但每个谓词仍必须返回证据/置信度。

### 6.2 五个终局谓词示例

**T01 HangCup**

```text
grasped(cup, L) ∧
contact(cup_handle, rack_hook) ∧
upright(cup) ∧
stable(cup, 0.5s) ∧
¬contact(cup, gripper)
```

- 关键：杯柄在挂钩上、杯身竖直、释放后 0.5s 不晃。
- 失败模式：杯柄没挂住/杯子倾斜/释放时带倒。

**T10 PlugCharger**

```text
grasped(strip, L) ∧ grasped(plug, R) ∧
axis_align(plug, socket) < 10° ∧
depth(plug, socket) > 0.8 × expected ∧
gap(plug, socket) < 2mm ∧
stable(plug, 0.3s)
```

- 关键：轴向对齐 + 插入深度 + 无间隙；视觉上看不到“电”，用几何。
- 失败模式：插头在插座外/只进一半/斜插。

**T27 StackBowls**

```text
on(bowl_3, bowl_2) ∧
on(bowl_2, bowl_1) ∧
center_offset(bowl_3, bowl_2) < 2cm ∧
¬interpenetrate(bowl_3, stack) ∧
stable(stack, 0.5s) ∧
¬contact(bowl_3, gripper)
```

- 关键：中心偏移、互穿、稳定；纸杯轻，释放后容易漂。
- 失败模式：没对准/叠歪/释放时吹倒。

**T19 ZipUp**

```text
zipper_progress(pouch) > 0.9 ∧
closed(pouch) ∧
stable(pouch, 0.3s)
```

- 关键：拉头行程；腕部相机看拉链；透明/布料用关键点，不强行 6D pose。
- 失败模式：拉链卡住/只拉一半/拉头脱轨。

**T14 PourOutMedicine**

```text
cap_open(bottle) ∧
pour_angle(bottle) > threshold ∧
pills_in(target) > 0 ∧
stable(bottle, 0.3s)
```

- 关键：瓶盖打开 + 药片出瓶；药片小，用目标区域计数/检测。
- 失败模式：盖没开/倒不出/倒到外面。

### 6.3 阈值校准

- **离线**：从官方 demo 的最终帧提取对象位姿，统计成功配置的分布；取 5–95% 分位作为初始阈值。
- **调试槽**：每个任务 10 次，记录谓词值和真人判定；用 precision/recall 调阈值。
- **保守门控**：只有当谓词置信度 >0.8 时才阻止释放/触发重试；低置信度时交给 VLA，避免误判。
- **每任务阈值表**：显式写入配置文件，版本化；不同任务不共享一个全局阈值。

### 6.4 误判处理

| 误判 | 后果 | 处理 |
|---|---|---|
| 假阳性（没成功判成功） | 提前结束，失败 | 保守阈值 + settle 二次确认 + 终局前多视角 |
| 假阴性（成功判失败） | 多余重试，可能弄坏 | 置信度门控 + 只重试一次 + 回滚点 |
| 对象跟丢 | 谓词失效 | 重新检测 + 上一帧 pose 先验 + 腕部视角 |
| 透明/反光 | 深度缺失 | 关键点/边缘/颜色 + VLA 提示；降级为 VLA-only |

## 7. 放置迁移（OPT）：容器系释放位姿

### 7.1 容器系

对每个放置类任务，定义目标容器/支撑的局部坐标系 \(F_c\)：

- 容器：由点云/包围体估计中心、主轴、开口平面；
- 支撑面：桌面/架子平面 + 法向；
- 释放位姿：对象在 \(F_c\) 中的 \(T_{obj}^{c}\)（位置 + 姿态）。

这样，测试时容器移动/旋转，释放位姿仍可迁移；不需要记住世界坐标。

### 7.2 从 K 条 demo 统计

对每个任务的成功 demo：

1. 取终局前释放帧的对象 pose 与容器 pose；
2. 计算 \(T_{obj}^{c}\)；
3. 用中位数 + MAD/协方差得到稳健中心与容差；
4. 按对象/容器类型分组（杯/碗/盒/袋/插座）。

输出：`release_pose_prior[task][object_type] = {median, cov, n}`。

### 7.3 测试时候选选择

```text
estimate F_c
candidates = sample around median (position ±2cm, yaw ±10°)
filter: clear(path) ∧ ¬collision(obj, container) ∧ stable(candidate)
score: Mahalanobis distance to demo median + clearance margin
choose argmin score
```

- 候选不要求精确 6D；对对称物体只优化位置 + yaw。
- 对插入类（T10/T26），候选是“预插入位姿 + 轴向”，不是释放位姿。
- 对堆叠类（T20/T27），候选是“中心 + 高度 + yaw”，并检查下层支撑。

### 7.4 回退

- 容器 pose 估计置信度低 → 用 VLA 的 2D 锚点/affordance，不用 6D；
- 对象是透明/可变形 → 用关键点/边缘，不用完整 6D；
- 候选全被过滤 → 选最接近 demo 中位数的候选，并降低释放速度。

## 8. 受控释放 + settle 验证（Guarded Release + SVL）

### 8.1 释放前门控

在 VLA 发出“张开夹爪”动作前，孪生检查：

1. 对象是否在目标区域内（`on/in/inserted` 的预条件）；
2. 是否 `clear(path)`、无碰撞；
3. 是否 `stable` 预判（支撑面法向、重心投影）；
4. 夹爪是否仍持有对象（`grasped` 置信度）；
5. 剩余时间是否足够一次重试。

任一项不满足 → 不释放；VLA 继续微调或重抓。

### 8.2 释放后 settle

```text
open gripper
wait 0.3–0.8s (task-dependent)
re-observe 2–3 frames
update object pose / contacts
evaluate final predicate
if success and stable: mark achieved, proceed
if failure and time_left > retry_budget: retry (micro-adjust / regrasp / alternate target)
if uncertain: take a second view (wrist/head) and re-evaluate
```

- 纸杯/轻物体等待更长（0.5–0.8s）；插头/刚性物体等待较短（0.3s）。
- 重试优先“微调”而不是“完全重来”：平移 5–10mm、旋转 2–5°、再释放。
- 每次重试前记录回滚点；如果重试把已完成步骤弄坏，回滚到上一个稳定状态。

### 8.3 重试预算

| 任务类型 | 预算 | 说明 |
|---|---:|---|
| 简单放置（T01/T02/T04） | 2 次 | 时间充裕 |
| 插入/闭合（T10/T19/T26） | 1–2 次 | 每次 10–20s |
| 堆叠/多步（T20/T27） | 1 次 | 重试可能弄倒 |
| 倒/倒出（T14） | 1 次 | 药片不可逆 |

- 用 `time_left_s` 动态分配；低于 30s 不再重试，保守结束。
- 重试次数写入日志，供离线分析。

### 8.4 与 VLA 的接口

VLA 的 prompt 不只是一个任务字符串，而是：

```text
[task instruction]
Current step: 3/3 — stack bowl 3 onto bowl 2.
Target: container frame (x,y,z,yaw) = ...
Constraint: keep stack stable; release only when centered within 2cm.
Previous attempt: failed (offset 3.1cm); adjust -2cm in x.
```

- 只给**步骤 + 目标 + 上一次失败原因**，不把整个对象图塞进 prompt。
- 视觉锚点可以渲染到输入图上（2D 目标框/中心线），降低语言歧义。
- 对 5 条复述，使用任务的标准指令 + 当前步骤; 不需要 160 条全量匹配。

## 9. 外部编辑 / 撤销恢复

### 9.1 无接触位移检测

每个 chunk 后比较对象图：

```text
if object pose delta > threshold
   and no robot contact / no gripper near object
   and not caused by robot motion
then external_edit = true
```

分类：

| 类型 | 例子 | 处理 |
|---|---|---|
| 平移 | human_1 把碗向下/向左移动 | 更新目标系；重新计算放置位姿 |
| 拿走 | 把目标物体拿走 | 重新检测/等待；若不可恢复则保守结束 |
| 撤销 | 拉链拉开/盖子打开/第二个碗拿走 | 回滚对应步骤；重做 |
| 重置 | 把物体放回起点 | 回滚到第一步；重新开始 |
| 阻挡 | 手挡住目标 | 等待/换路径；不要硬撞 |

### 9.2 官方 human 备注映射

官方 `generalization.human_1_note` / `human_4_note` 给出每任务剧本（[S3][S4]）：

- T27：human_1 把粉色碗向下移动；human_4 叠了第二个之后拿下第二个（先叠后撤 = undo）。
- T19：human_1 把包向左移动；human_4 拉上拉链之后拉开。
- T14：human_1 拧开盖子之后拧动回来。
- T17：human_4 笔盒合上之后手动打开。
- T24：可乐/薯片快到了然后放回传送带起点（运动中干扰）。

这些备注可以直接转成**状态 diff 测试用例**：在回放/调试槽里注入同样的编辑，测谓词检测延迟和恢复成功率。

### 9.3 回滚策略

- 每个步骤记录 `stable_state`（对象图快照 + 夹爪状态）。
- 检测到 `undone` → 回滚到该步骤开始前的稳定状态，只重做该步骤，不重做整个任务。
- 如果连续两次回滚失败 → 放弃该步，保守结束，保留部分分（success 已无望时）。
- 如果人为干扰是“拿走目标物体”且无法恢复 → 不浪费时间，按失败处理。

## 10. 单模型合规、数据与延迟

### 10.1 合规阶梯

| 档 | 感知 | 合规性 | 使用条件 |
|---|---|---|---|
| **L0 孪生-lite（默认）** | 立体深度 + 平面 + 颜色/边缘 + VLA 特征；无额外学习模型 | 最安全 | 直接上线 |
| **L1 固定感知工具** | 开放词表检测/分割/6D pose（如 SAM 2 / FoundationPose）[S21][S22] | 需披露；可能被解释为多模型 | 仅当官方确认“感知工具不算第二个策略模型” |
| **L2 纯 VLA 回退** | 无孪生，只用步骤提示 + 站姿先验 | 最保守 | L0 精度不够或延迟超预算 |

**论证**：手册禁止“不同任务用多个模型”，不是禁止“固定感知工具”。但我们不赌解释，默认 L0；L1 只作为增强，且在模型卡写清“同一套固定感知工具，不为任务切换模型”。

### 10.2 数据

- 主路径只用官方 32 任务数据；不假设外部/合成数据被允许（手册只读到 2.2）。
- 感知工具若是预训练模型，只做推理，不用外部机器人数据微调；如果手册禁止外部预训练，退回 L0。
- 谓词阈值只用官方 demo + 调试槽校准，不引入外部标签。

### 10.3 延迟

- 孪生在 chunk 边界跑；VLA chunk 16–30 动作；孪生 <200ms。
- 立体深度可 10Hz；检测/pose 只在关键帧（抓取前、释放前、释放后）。
- 如果延迟超预算：降分辨率、跳检测、只跟踪当前对象，不全局重建。

### 10.4 失败隔离

- 孪生异常 → 不影响 VLA 主循环；降级为 VLA-only，记录错误。
- 谓词超时 → 用上一次状态 + 保守门控；不阻塞动作。
- 感知丢对象 → 用上一帧 pose + 腕部视角；仍失败则重检测。

## 11. 实验计划

### 11.1 离线（第 1–2 周）

**E1 谓词精度**

- 数据：6 个代表任务（T01/T10/T14/T19/T27/T07），每任务 30–40 条成功/失败 episode，共 200 条。
- 标注：人工看最终帧/释放后 0.5s，标 step success。
- 指标：precision/recall/F1；release-gate 的假阳性/假阴性。
- 通过：precision > 0.9，recall > 0.8；否则调阈值/降级。

**E2 放置迁移**

- 数据：每任务 K=20–50 条成功 demo；留出 20% episode。
- 方法：容器系中位数 vs 世界坐标中位数 vs VLA-only。
- 指标：离线重放/几何检查的放置成功率、碰撞率、稳定性。
- 通过：容器系比世界坐标高 >5pp；否则容器 pose 估计有问题。

**E3 外部编辑检测**

- 数据：官方 human 备注 + 合成 state diff（平移/拿走/撤销/重置）。
- 指标：检测延迟（chunk 数）、误报率、恢复成功率。

### 11.2 真机调试槽（第 3–5 周）

**E4 站姿先验**（1 天）：T01/T10，A/B/C 三组，各 10 次。

**E5 终局 A/B**（每任务 10–20 次）：

- 任务：T01（挂杯）、T10（插充电器）、T27（叠碗）。
- 基线：VLA + 零 pivot + 固定 chunk。
- 处理：VLA + 站姿先验 + SODT release/settle。
- 指标：终局 success、步骤分、重试次数、耗时、误判。
- 通过：至少 2/3 任务 +5pp success；否则回退。

**E6 人为干扰**（每任务 10 次）：注入 T27/T19/T14 的官方 human 剧本；测恢复。

### 11.3 全量（第 6–7 周）

- 32 任务 × 10 次 = 320 trials；先跑 1 次全量，按任务聚类分析。
- 主指标：总平均 success；次指标：总平均 step（tie-break）。
- 统计：任务层配对 bootstrap；320 trials 的二项 SE≈2.56pp，但任务内相关，实际有效样本更低；不要只看总数。
- 通过：success +3–6pp；step 不下降；延迟/稳定性达标。

### 11.4 可证伪与停止规则

| 条件 | 动作 |
|---|---|
| E1 precision <0.8 | 放弃 release gate，只保留提示/日志 |
| E4 站姿无差异 | 保持示例 pivot 语义，不再投入 |
| E5 <2/3 任务 +3pp | 放弃 SODT 主路径，退回 VLA + 提示 |
| 延迟 >200ms/chunk 或动作频率 −20% | 降级 L0/跳检测 |
| E6 恢复 <20% | 只做检测/日志，不做回滚 |

## 13. 创新点与 novelty 声明

| 编号 | 创新点 | 技术声明 | 与现有工作的差异 |
|---|---|---|---|
| I1 | SODT 步骤可观测孪生裁判 | 对象图 + 官方 score_steps 谓词 + 在线判定 | 现有孪生用于训练/重建/评估/预测，不用于推理期步骤裁判 |
| I2 | Step Predicate DSL | 十类基础几何/语义谓词 + 任务特定扩展 + 证据/置信度 | 不是通用 success classifier，任务图显式可读 |
| I3 | Guarded Release + SVL | 释放前门控 + 释放后 settle + 微调重试 | 直接打终局静默失败；现有 VLA 多为 open-loop |
| I4 | 容器系放置迁移 | 容器局部系释放位姿统计 + 支撑/碰撞过滤 | 比世界坐标迁移更稳；比端到端模仿更可解释 |
| I5 | 外部编辑 diff / undo | 无接触位移检测 + 步骤回滚 + 最小重做 | 利用官方 human 备注；不是随机噪声鲁棒 |
| I6 | 立体度量锚 | 双目 + 桌面平面 + 站高恢复米制 | 固定基座下便宜、稳定；不依赖深度传感器 |
| I7 | 站姿先验 | 32 任务 pivot 均值替代全零；绝对/增量 A/B | 1 天可验证的接口级收益 |
| I8 | 单模型合规阶梯 | L0 孪生-lite → L1 固定工具 → L2 纯 VLA | 主动规避“多模型”解释风险 |
| I9 | 专利感知模块化 | 裁判不控制；不做轨迹/RL/分层动作 | 避开 CN120552084B/US12638859B2/CN120941414B |
| I10 | 离线孪生校准 | demo 最终状态 + 调试槽阈值 | 无需真机即可先做；可回放 |

**Novelty 一句话**：现有工作把数字孪生当训练环境、重建结果或评估工具；我们把**官方评分步骤**变成**推理时可观测的对象级谓词**，让孪生只做“成功裁判 + 重试触发器”，从而在单模型约束下直接提升 success。

## 14. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 谓词误判 | 提前结束/多余重试 | 保守阈值 + settle 二次确认 + 置信度门控 |
| 透明/可变形对象 | 6D pose 失败 | 关键点/边缘/affordance + VLA；不承诺全物理 |
| 容器 pose 估计差 | 放置迁移错 | 多视角 + 平面/包围体；置信度低时回退 VLA |
| 头部双目精度有限 | 放置/插入偏差 | 腕部近距 + ICP + 视觉伺服；头部只做全局 |
| 重试破坏已成功步骤 | success 下降 | 回滚点 + 只重试当前步 + 预算上限 |

| 外部数据限制 | 不能用感知预训练 | L0 经典几何；邮件确认 |
| 开源 VLA 预训练权重是否算外部数据 | 合规风险 | 邮件确认；默认官方数据微调；模型卡披露底座 |
| 底座是扩散式/分层式 VLA | 可能增加专利重叠 | 优先非扩散/非分层底座；SODT 本身不增加该风险；完整 claim chart |

| 榜单占位 | 误判难度 | 只当结构先验；不引用为真实排名 |
| 任务 info 抓取被风控 | 数据缺口 | 缓存 + 多通道；标注抓取日期 |

## 16. 结论

**第 8 轮的核心不是“更大的模型”，而是“让模型知道自己有没有成功”。** 双足数据说不要走位；专利地图说不要做控制侧孪生；文献说对象级窄孪生可行；官方手册说 success 是唯一主键。四者交汇成一个可执行系统：**SODT / Referee Twin**——固定站姿的立体几何建对象图，32 个官方评分步骤变谓词，释放后 settle 验证，人为撤销回滚，失败最小重试；学习侧只有一个 VLA。

**一句话押注**：**用“步骤可观测的孪生裁判”把静默失败变成可重试的失败；不造全物理孪生，不造更大 VLA，不走位。**
