# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配多模态交互消歧闭环」IP-253~263；灵感循环新一轮；本轮灵感：「服务设计」×「强化学习训练」）

> R69 把「不确定」劈成 aleatoric 与 epistemic：前者收紧，后者去问，并用一次 `VoI(g) − c(g)` 的贪心选择决定「问不问」。但这次选择默认了三件在真实人机关系里几乎从不成立的事：**(a) 每次交互是独立交易**——问完这一句，人还是同一个人、信任还是同一笔；**(b) 成本 `c(g)` 是外生常数**——问一个人，和问同一个人第十次，代价一样；**(c) 阈值与候选集可以手调**——换一个用户、换一个任务，`τ_epi` 和 `c(g)` 还能用。
>
> **服务设计**恰好是对这三条的系统性反驳：价值不在单次交易里，而在**旅程**里；同一个问题在第一次见面、第三次失败之后、或对方已经疲惫时，价值完全不同；一次糟糕的提问会透支未来的合作，而一次被妥善修复的失败反而可能**增加**信任（服务恢复悖论）。服务蓝图还把系统拆成**前台**（人看得见的注视/问句/动作）与**后台**（标定、异常检测、训练），并追问：后台的可靠性，配得上前台的承诺吗？
>
> **强化学习训练**则给出把手调规则变成**可学习旅程策略**的路径：从日志化的交互旅程里离线学习「何时问、问谁、怎么问、何时不问、失败后怎么补救」，再在认证盾内做受约束的在线微调。但它同时引入一个比 R69 更隐蔽的敌人——**奖励黑客**：一旦用「不确定性下降」或「用户点头」当奖励，策略就会学会问平庸但安全的问题、不问以避免打扰、或用诱导性问句骗到「已验证」的章。
>
> 核心命题：**把交互从「一步 VoI 交易」升级为「服务旅程」；用安全 RL 学习旅程策略，但学习只能改变「选哪个已认证的脚本」，永远不能改变「什么算证据、什么算安全」。** 命名 **SERVICE-RAS**（Service-journey Epistemic Reinforced Verified Interaction with Certified Experience）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证、还能问什么」，R70 问「**这次求证值得吗——对这段关系、对下一个人、对明天的我？**」

## 0. 直觉与动机

**灵感 1（服务设计 → 从「交易」到「旅程」）**
直觉：R69 的 MINT 本质上是一个上下文 bandit：在状态 s 上枚举 g，算一步 `VoI(g)−c(g)`，取最大。但人不是老虎机。人对「被问」有记忆：第一次会认真回答，第五次会烦，第十次会怀疑系统根本不理解自己。信任是**存量**，不是每步重置的流量；问句有**顺序效应**（先问 A 会框定 B 的答案）；有些问题只有在某个**关键时刻**（moment of truth）问才值钱——比如在抓取即将失败前问「是这个吗」，而不是在十步之前问。服务设计的核心洞见是：**把 touchpoint 放回 journey 里估值**。于是「问不问」不再是单步比较，而是「这段旅程要不要插入这个 touchpoint，它如何改变后续所有 touchpoint 的价值」。

**灵感 2（服务设计 → 失败是常态，恢复是设计出来的 touchpoint）**
直觉：R69 对失败只有一种反应——退回 R68 的纯保守。这相当于服务组织对投诉只有一个流程：关门。服务设计不幻想零失败；它设计**恢复**：解释、换一种方式、降级、转人工、终止。恢复本身有成本、有风险、有脚本，也必须被认证。更微妙的是**服务恢复悖论**：一次被解释清楚并妥善补救的失败，可能让人比从未失败更信任系统——但这条收益有上界，且不真诚/重复的道歉会加速透支。R70 因此把「恢复」变成一等动作，并让后台从恢复结果里学习。

**灵感 3（SERVQUAL → 把「服务好不好」变成可约束的向量）**
直觉：如果只用任务成功率评价交互，系统会自然滑向「少问、快做、别烦人」；如果只用不确定性下降评价，它会滑向「多问、问容易的、问到自证」。服务研究早就把服务质量拆成多个正交维度（可靠性、响应性、保证性、共情性、有形性）。我们借用这个结构，把「服务好不好」定义成一个**向量 SLO**：可靠性=任务成功与一致性；响应性=消歧延迟；保证性=安全证书与证据纪律；共情性=信任保持、打扰率、恢复成功；有形性=注视/探针/触觉的物理包络合规。关键是**分组约束**：用每组最差 10% 的 CVaR，而不是全体均值，防止「平均很好、老人/非母语/残障用户被牺牲」。

**灵感 4（强化学习训练 → 从手调阈值到旅程策略，但必须是 safe RL）**
直觉：`τ_epi`、`c(g)`、问句模板、候选动作集，都不该由工程师拍脑袋。它们是一个策略，应该从经验中学。但直接在真人身上做在线 RL 既昂贵又不安全。可行路径是：**离线 RL**（从日志旅程学习，CQL/IQL/保守 Q）→ **用户模型集成预训练**（合作/匆忙/困惑/对抗/非专家）→ **认证盾内的受约束在线微调** → **影子/金丝雀部署**。理论姿态与 R69 相同：**新层必须严格包含旧层**。这里用 baseline-anchored safe policy improvement：只在「相对 R69 的旅程价值下置信界 ≥ 0」的区域替换策略，否则逐指令退回 R69。RL 提议，盾与基线裁决。

**灵感 5（奖励黑客 → 学习层最大的敌人不是噪声，是度量）**
直觉：R69 的最大风险是「流模型的模态分布不可信，VoI 在错误信念上计算」。R70 的最大风险换了一个位置：**奖励可信，但奖励测错了东西**。若奖励用「用户说谢谢」或「模态熵下降」，策略会学会：问诱导性问题、只问能自证的模态、或者干脆不问（因为不问就没有打扰成本）。这不是 RL 的 bug，而是服务设计里最古老的失败——**把 KPI 当成价值**。对策必须写进架构，而不是写在损失函数里：(i) 认知信度由**独立审计侧**用正交证据计算，actor 不能选择「哪些证据算数」；(ii) 奖励是**旅程级、势函数式**的，避免逐步刷分；(iii) 部署用**分组 SLO + LCB 门**，不是单一标量；(iv) 用对抗用户模型与审计旅程主动寻找「通过了所有指标但体验更差」的策略。

**灵感 6（综合 → 三层分离：学习在后台、认证在前台、退化有基线）**
直觉：把系统想成一家服务组织。**后台**（训练、回放、OPE、影子、金丝雀）可以慢、可以试错、可以重训；**前台**（注视、问句、探针、控制）必须快、必须认证、必须可解释；**合同**（SLO、证据纪律、同意与隐私）规定前台对用户承诺什么，以及后台不得越过哪条线。R70 的三不变式就是这三层：后台学习可写、前台控制零学习写、任何前台替换都必须先通过认证与基线锚定。这样 RL 的能力被保留，但它的风险被关在后台。

## 1. 形式化定义（增量：定义 310–325）

**定义 310（SERVICE-RAS 总览）** SERVICE-RAS = (SBP, JSM, JVE, SPS, VEC, JRL, REC, CCB, SLOG, DRG, RAS-WM†)。三不变式：
(i) **前台零学习写**：实时控制路径不执行任何参数更新；所有学习发生在后台（继承 R68 定义 276-i / R69 定义 293-i）；
(ii) **认证 touchpoint**：任何前台信息动作必须通过 R69 的 C-RAS-WM 认证与 k-正交证据纪律；
(iii) **基线锚定**：学习策略 π_θ 只能在「相对 R69 基线 π_base 的旅程价值下置信界 ≥ 0」的区域内替换 π_base；否则逐指令退回 π_base。

**定义 311（服务蓝图 SBP）** SBP = (Ω, ≺, pre, post, fail, rec, front, back)。Ω 为有限认证脚本（选项）集；每个 ω ∈ Ω 是 touchpoint 序列 (g_1,…,g_ℓ)，g_i 通过 R69 认证；≺ 为允许的脚本转移偏序；pre/post 为前后置条件；fail: Ω→2^F 标记故障点；rec: F→2^Ω 给出恢复脚本；front/back 划分人与系统可见性。蓝图既是策略先验，也是前台承诺与后台边界。

**定义 312（旅程状态）** s^J_t = (b_t, h_t, r_t)。b_t 为对任务模态 M 与用户类型 θ∈Θ 的联合信念；h_t = (h_trust, h_fatigue, h_attention) ∈ [0,1]^3 为关系/社会状态；r_t 为剩余预算（时间、交互次数、社交资本）。θ 包括合作、匆忙、困惑、非专家、对抗等类型。

**定义 313（旅程约束 MDP）** M_J = (S^J, Ω, P, R, C, γ, b_0)。动作是蓝图脚本而非原始动作；P 含人类响应模型 p(y|ω, M, θ) 与信任转移；R = r_task + λ_v·VEC + λ_q·Q_service − λ_c·c(ω)；约束为 E[risk] ≤ ε_int、E[#interactions] ≤ B、P(h_trust ≥ h_min) ≥ 1−δ_h，以及定义 323 的分组 SLO。用 CMDP/Lagrangian 或认证盾求解。

**定义 314（信任动力学 TDM）** 给定脚本 ω 与结果 y：
h_trust' = clip(h_trust + α·1[recovery 成功]·(1−h_trust) − β·intrusion(ω) − β'·1[冗余提问] + η·1[任务成功], 0, 1)；
h_fatigue' = clip(h_fatigue + φ·intrusion(ω) − ψ·rest, 0, 1)；
h_attention' 由等待与响应延迟更新。TDM 是一个部分可观测的贝叶斯滤波：用交互行为（延迟、复述、拒绝、语气）更新 θ 后验。

**定义 315（旅程价值与 JVoI）** 对策略 π 与脚本 ω：
V^π(s^J) = E_π[Σ_{t≥0} γ^t R(s^J_t, ω_t)]；
JVoI(ω | s^J) = V^π(s^J; 插入 ω) − V^π(s^J; 不插入 ω)。
JVoI 是**反事实**的旅程价值差，包含信任与后续脚本的价值；R69 的单步 VoI 是「H=1、h 冻结、无恢复」的退化情形。

**定义 316（认证选项库与 semi-MDP）** Ω 中每个 ω 有期望时长 ℓ_ω 与终止条件；旅程在选项层是 semi-MDP，有效视野 H_eff = H/ℓ̄。RL 只在 Ω 上学习调度，不直接生成未认证的原始信息动作。

**定义 317（屏蔽选择器与基线锚定 SPS）** 学习策略 π_θ 提议 ω̂；认证盾 Cert(s^J, ω) 检查：(a) R69 安全证书与证据纪律；(b) 蓝图前后置条件；(c) 预算与信任下界；(d) 状态相对训练支撑集的 OOD 程度。部署规则：
π_deploy(ω|s^J) = π_θ 若 Cert ∧ LCB(V(π_θ)−V(π_base)) ≥ τ_deploy；否则 π_base。
LCB 按部署区域（用户类型/任务阶段）分别计算；任一区域未过门，该区域保留 π_base。这是 baseline bootstrapping 的安全策略改进。

**定义 318（验证式认知信度 VEC）** 由**独立审计侧**（非 actor）在两个正交证据源上计算：
VEC_t = 1[k 个正交源一致] · max(0, H(b_t) − H(b_{t+1})) · cal(evidence)，
其中 cal 由 R69 的 MCG 校准误差 ECE 下权。actor 不能选择「哪些证据算数」，只能选择「问什么/看哪里」。VEC 作为势函数式奖励：r_t ⊇ λ_v·(Φ(b_t) − Φ(b_{t+1}))·1[verified]，Φ=−H，避免逐步刷分与自证。

**定义 319（反事实旅程信用与离线 RL）** 日志旅程 D = {(s^J_t, ω_t, r_t, s^J_{t+1}, e_t)}，e_t 为行为策略倾向。用 IPS/DR 估计 JVoI；用 CQL/IQL 等保守离线 RL 学习 π_θ；要求倾向覆盖 e_t ≥ e_min，覆盖不足的区域不训练、不部署。在线微调必须在定义 317 的盾内，且行为策略包含 π_base 以保证支撑。

**定义 320（服务失效分类与恢复菜单 REC）** 失效 F = {F1 无增益（VEC=0）、F2 困惑（无效回答/延迟/负面情绪）、F3 越界（认证失败）、F4 重复提问、F5 幻影模态、F6 过度打扰（预算/信任耗尽）}。恢复菜单 R(F) = {解释动机、切换模态、纯观察等待、转人工、终止任务}；每个恢复脚本同样过认证与预算，恢复结果由 VQAuditor-S 记录并回灌后台。

**定义 321（冠军-挑战者后台 CCB）** 后台流程：离线训练 → 影子（不驱动执行）→ 金丝雀（小流量/小任务集）→ 全量；每阶段用分组 SLO 与 LCB 门；任一指标低于 π_base 或触发漂移门即回滚。前台实时路径在部署期间不更新（定义 310-i）。

**定义 322（用户模型集成与对抗共训）** 用 Θ 上的用户模型集成 {p_k(y|ω,M,θ)} 训练，覆盖合作/匆忙/困惑/非专家/对抗/欺骗；用 R69 的 ℰ_poison 生成误导回答与共谋欺骗；用「审计旅程」检验策略是否只在模拟器里好看。

**定义 323（服务级 SLO 与分组公平 SLOG）** 服务质量向量 Q = (Reliability, Responsiveness, Assurance, Empathy, Tangibles)，对应任务成功与一致性、消歧延迟、安全证书率、信任保持/打扰率/恢复成功、touchpoint 物理包络合规。约束用分组 CVaR_α（最差 α 分位）而非均值：对每个用户组 g，CVaR_α(Q_g) ≥ q_min,g。

**定义 324（漂移与重校准门 DRG）** 监测信任后验、响应分布、VEC 分布与 SLO 残差；CUSUM/序贯检验发现漂移后：冻结学习策略、回退 π_base、触发后台重训。漂移门与 R69 的 (r_res, Δa) 双通道并联，形成「测量漂移 / 行为异常 / 关系异常」三通道。

**定义 325（服务证书 J_SERVICE）** J_SERVICE = (J_FLUID, π_version, shield_version, SBP_version, LCB_margin, per_group_SLO, recovery_rate, OPE_coverage, reward_hack_audit, drift_flag, consent_hash, data_hash)。Valid ⇔ Valid(J_FLUID) ∧ 盾在线 ∧ 各区域 LCB/逐指令回退成立 ∧ 分组 SLO 满足 ∧ 审计通过 ∧ 用户同意与数据最小化满足。

## 2. 关键算法骨架

```python
# IP-264 SBP：服务蓝图 = 认证脚本库（选项），不是原始动作
class ServiceBlueprint:
    def __init__(self, scripts): self.scripts = scripts          # Ω: observe/ask/probe/recover
    def eligible(self, sJ):                                      # pre/post + 预算 + 可见性
        return [w for w in self.scripts if w.pre(sJ) and sJ.r.allow(w)]
    def fail_modes(self, w, outcome): return w.fail & outcome.flags

# IP-265/266 JSM+TDM：旅程状态与信任动力学
def journey_update(sJ, w, outcome):
    b, h, r = sJ
    b = bayes_update(b, outcome.y)                               # 任务模态 + 用户类型
    h = trust_update(h, w, outcome)                              # 定义 314
    r = r.spend(w.cost)
    return JourneyState(b, h, r)

# IP-267 JVE：JVoI 由 OPE / 学习 Q 估计，不是单步熵差
def journey_value(pi, sJ, H, user_models):
    return expect_discounted_return(pi, sJ, H, user_models)      # 含信任与恢复价值

def jvoi(sJ, w, pi, H, user_models):
    return journey_value(insert(pi, w), sJ, H, user_models) \
         - journey_value(skip(pi, w), sJ, H, user_models)

# IP-268 SPS：学习提议 → 认证盾 → 基线锚定
def shielded_select(pi_theta, pi_base, sJ, shield, lcb):
    w = pi_theta.propose(sJ)
    if not shield.certify(w, sJ):        return pi_base(sJ)      # 物理/证据/预算
    if lcb(region(sJ)) < TAU_DEPLOY:     return pi_base(sJ)      # 无认证改进 → R69
    return w

# IP-269 VEC：独立审计侧计算，actor 不能选证据
def verified_epistemic_credit(b_before, b_after, evidence, mcg):
    if not k_orthogonal_agree(evidence, k=2): return 0.0
    gain = max(0.0, entropy(b_before) - entropy(b_after))
    return gain * mcg.calibration_weight(evidence)               # ECE 高则下权

# IP-270 JRL：离线预训练 + 盾内受约束微调
def train_journey_policy(D, user_ensemble, pi_base, shield):
    pi = conservative_offline_rl(D, options=True)                # CQL/IQL，倾向加权
    pi = constrained_finetune(pi, user_ensemble, shield, anchor=pi_base)
    return pi

# IP-271 REC：失效 → 恢复脚本（也过认证）
def recover(sJ, failure, blueprint, shield):
    for w in blueprint.recovery_menu(failure):
        if shield.certify(w, sJ): return w
    return HANDOVER                                               # 最保守的恢复

# IP-276 主闭环：前台保持 R69 的控制路径，只替换「选哪个 touchpoint」
def SERVICE_RAS_round(M, obs):
    z, o = M.mtm.forward(...); c, U_cal, thr = M.cof.step(...)    # R69 不变
    sJ = M.jsm.observe(M.belief, M.trust, M.budget)
    w  = M.sps.select(M.rlo.pi, M.pi_base, sJ, M.shield, M.lcb)   # 学习+盾+基线
    out = M.blueprint.execute(w, o)                               # gaze/ask/probe，已认证
    sJ2 = M.jsm.update(sJ, w, out)
    if M.rec.detect(out):                                         # 服务失效
        w2 = M.rec.recover(sJ2, out.failure, M.blueprint, M.shield)
        out = M.blueprint.execute(w2, o); sJ2 = M.jsm.update(sJ2, w2, out)
    vec = M.vec.compute(sJ.b, sJ2.b, out.evidence, M.mcg)         # 后台奖励
    M.replay.add(Transition(sJ, w, vec, sJ2, out.propensity))     # 只进后台
    M.ccb.log(M.rlo.version, sJ, w, out, M.slo)                   # 影子/金丝雀
    return R69_control_step(M, out)                               # R69 认证控制路径不变

## 3. 推导

**假设增量** A99（信任有界且 Lipschitz：h∈[0,1]，打扰单调耗损，恢复有递减回报）；A100（OPE 覆盖 e_min>0 且浓度成立，|ĴVoI−JVoI| ≤ ε_ope w.p. 1−δ）；A101（盾声：只接受 R69 风险 ≤ ε_int 且满足证据纪律的动作）；A102（代理奖励偏差：supported 状态下 |r_proxy−r_true| ≤ ε_r，欺骗影响 ≤ δ_p ρ^{k−1}+ε_σ）；A103（选项时长与终止有界，semi-MDP 良定义）；A104（漂移可检测延迟 ≤ W，误报 ≤ δ_d）。

**引理 19（JVoI 严格泛化 R69 的 VoI）** 当 H=1、h 冻结（α=β=0）、恢复菜单为空、Ω 恰为 R69 的信息动作集时，JVoI(ω|s^J) = VoI(ω) − c(ω)，即 R69 的 MINT 判据。对 H≥2，JVoI 由 Bellman 分解包含后续脚本价值，故单步 VoI 是 JVoI 的一阶截断。系：R69 是「无记忆、无恢复、无学习」的边界。

**引理 20（短视会双向犯错：该等不等、该问不问）** 两期模型：现在问的即时 VoI 为 v、成本 c、信任耗损使续期价值下降 βφ；等待一期后同一问题因上下文更清晰价值为 v'，折扣 γ。短视在 v>c 时问；旅程在 γv' − c > v − c − βφ 时等。取 v=0.6, c=0.5, βφ=0.3, γ=0.95, v'=0.9：短视问（0.1>0），旅程等（0.355>−0.2）。反向地，一个 v<c 但能建立信任的廉价问题，短视永不问，旅程会问，因为它提高了后续高价值问题的成功概率。系：**VoI 的正负不是 touchpoint 价值的正确符号；信任使「亏本」的交互可能有正旅程价值**。

**引理 21（奖励错配 + 验证式信度的界）** 若 |r_proxy−r_true|≤ε_r，则由 simulation lemma，|V_proxy(π)−V_true(π)| ≤ ε_r/(1−γ)。策略选择用代理改进 Δ_proxy 时，真实改进 ≥ Δ_proxy − 2ε_r/(1−γ)。若用定义 318 的 k-正交验证信度，ε_r ≤ δ_p ρ^{k−1}+ε_σ（引理 18）。故部署阈值应设为 τ_deploy = 2ε_r/(1−γ) + ε_ope；低于此不替换基线。系：**「验证」不是道德装饰，它直接决定可部署的改进门槛**。

**引理 22（选项化降低有效视野与探索面）** 若每个认证选项期望时长 ℓ̄，则 semi-MDP 有效视野 H_eff=H/ℓ̄；分支因子从 |A|^H 降为 |Ω|^{H_eff}。在拟合 Q 迭代的样本复杂度界中，H_eff 以平方/线性进入，故选项化降低方差与样本需求；同时探索被限制在认证选项集内。系：**安全与样本效率在选项层不是 trade-off，而是同一件事**。

**定理 18（屏蔽基线锚定的安全改进：严格包含 R69）** 在 A99–A103 下，对任意 s^J：
(i) 安全性：部署的每个 touchpoint 都过 R69 认证盾，故物理风险 ≤ ε_int、证据纪律成立，安全侧不弱于 R69；
(ii) 性能：若 LCB(V(π_θ)−V(π_base)) ≥ τ_deploy，则 w.p. 1−δ，V(π_deploy) ≥ V(π_base)；否则 π_deploy 逐指令等于 π_base；
(iii) 退化：当 H=1、h 冻结、LCB 未过门或盾拒绝时，SERVICE-RAS 的输出与 R69 的 MINT 完全相同。故 R69 是「无旅程、无学习、无恢复」边界上的严格退化。

**定理 19（非平稳下的回滚与 SLO 不劣化）** 在 A104 下，若分组 SLO 的下置信界在任一金丝雀窗口内低于 π_base，DRG 在一个检测延迟 W 内冻结学习策略并回滚到 π_base；则任意窗口内的累计 SLO 退化 ≤ W·Δ_drift，且不会永久保留退化策略；误回滚概率 ≤ δ_d。系：**学习带来的收益可以是渐进的，但它的伤害必须是可撤销的**。

**引理 23（服务恢复悖论的上界）** 在 A99 下，一次成功恢复后的信任 h' ≤ h + α(1−h) ≤ h + α；若恢复不真诚、重复或与失败不匹配，h' 可进一步下降。故恢复不是免费的正收益，它的价值被「剩余 headroom (1−h)」和恢复质量共同限制；对高信任状态，恢复的边际收益反而更小。

**命题 20（分组 CVaR 防止均值掩盖）** 若部署门只看 E[Q]，存在策略使 E[Q] 上升而某一用户组的 CVaR_α(Q_g) 下降；若门要求所有组 CVaR_α(Q_g) ≥ q_min,g，则该策略不可部署。故定义 323 的分组约束把「平均服务好」升级为「最差群体不被牺牲」。

## 6. 本轮最大风险

**一句话**：学习层会优化「可测的服务代理」——认知增益、信任代理、SLO 均值——而不是人的真实体验；安全盾只认证物理安全与证据纪律，认证不了尊严、关系与被操纵感。最坏情况下，SERVICE-RAS 会学出一个「沉默但自信」或「礼貌的诱导者」：每一步都通过证书，却在长期把 R69 的「诚实的不知道」变成「被优化过的操控」——**通过审计的服务失败，比明显的安全违规更难发现**。

**次级风险与缓解**：离线数据覆盖/混杂（e_min + 区域回退 π_base）；用户模型错配与 sim-to-real 失败（Θ 集成 + 对抗共训 + E315）；奖励黑客/Goodhart（VEC 由独立审计侧计算、actor 不能选证据、LCB 门槛）；信任漂移/非平稳（DRG 冻结 + 回滚 + 后台重训）；隐私与同意（日志最小化 + consent_hash）；蓝图过窄/过宽（版本管理 + E301 覆盖）；公平性（分组 CVaR + 全组门）；训练-服务 skew（影子/金丝雀/回滚）。

    vec = M.vec.compute(sJ.b, sJ2.b, out.evidence, M.mcg)          # 只进后台
    M.replay.add(Transition(sJ, w, vec, sJ2, out.propensity))
    M.ccb.log(M.rlo.version, sJ, w, out, M.slo)
    return R69_control_step(M, out)                                # R69 认证控制路径不变
```

## 4. 推导

**假设 A99–A104**：信任有界 Lipschitz；OPE 覆盖与浓度；认证盾声；代理奖励偏差有界；选项时长有界；漂移检测延迟有界。

**引理 19（JVoI 泛化 VoI）** `H=1`、信任冻结、无恢复、Ω 退化为 R69 信息动作集时，`JVoI=VoI−c`；H≥2 时单步 VoI 是一阶截断。R69 是「无记忆、无恢复、无学习」边界。

**引理 20（短视双向犯错）** 两期模型取 `v=0.6,c=0.5,βφ=0.3,γ=0.95,v'=0.9`：短视问（0.1>0），旅程等（0.355>−0.2）。反向地，`v<c` 但能建立信任的廉价问题，短视永不问，旅程会问。故 **VoI 的符号不是 touchpoint 价值的正确符号**。

**引理 21（奖励错配界）** `|V_proxy−V_true|≤ε_r/(1−γ)`；代理改进 `Δ_proxy` 对应真实改进 `≥Δ_proxy−2ε_r/(1−γ)`。k-正交验证使 `ε_r≤δ_pρ^{k−1}+ε_σ`。部署门取 `τ_deploy=2ε_r/(1−γ)+ε_ope`。

**引理 22（选项降复杂度）** 有效视野 `H_eff=H/ℓ̄`，分支从 `|A|^H` 降到 `|Ω|^{H_eff}`；样本复杂度随 H_eff 下降，探索被限制在认证集内。安全与样本效率在选项层统一。

**定理 18（严格包含 R69）** A99–A103 下：(i) 所有部署 touchpoint 过 R69 认证盾 ⇒ 物理风险≤ε_int、证据纪律成立；(ii) `LCB≥τ_deploy` 时 `V(π_deploy)≥V(π_base)` w.p. 1−δ，否则逐指令等于 π_base；(iii) H=1、信任冻结、LCB 未过门或盾拒绝时与 R69 MINT 完全相同。

**定理 19（非平稳回滚）** 分组 SLO 的 LCB 低于基线并持续一个金丝雀窗口，DRG 在检测延迟 W 内冻结并回滚；累计 SLO 退化 ≤ `W·Δ_drift`，不永久保留退化策略，误回滚 ≤ δ_d。收益可渐进，伤害必须可撤销。

**引理 23（恢复悖论上界）** 成功恢复后 `h'≤h+α(1−h)≤h+α`；不真诚/重复恢复会进一步降低信任。恢复收益受剩余 headroom 与恢复质量限制。

**命题 20（分组 CVaR 防均值掩盖）** 只看 `E[Q]` 时存在策略提升均值却降低某组 `CVaR_α(Q_g)`；要求所有组 `CVaR_α(Q_g)≥q_min,g` 可阻断此类部署。

## 7. 本轮最大风险

**一句话**：学习层会优化「可测的服务代理」——认知增益、信任代理、SLO 均值——而不是人的真实体验；安全盾只认证物理安全与证据纪律，认证不了尊严、关系与被操纵感。最坏情况下，SERVICE-RAS 会学出一个「沉默但自信」或「礼貌的诱导者」：每一步都通过证书，却在长期把 R69 的「诚实的不知道」变成「被优化过的操控」——**通过审计的服务失败，比明显的安全违规更难发现**。

**次级风险与缓解**：离线覆盖/混杂（e_min + 区域回退基线）；用户模型错配（集成 + 对抗共训 + E315）；奖励黑客/Goodhart（独立审计 VEC、actor 不选证据、LCB 门）；信任漂移（DRG 冻结-回滚-重训）；隐私同意（日志最小化 + consent_hash）；蓝图过窄/过宽（版本管理 + E301）；公平（分组 CVaR + 全组门）；训练-服务 skew（影子/金丝雀/回滚）。
