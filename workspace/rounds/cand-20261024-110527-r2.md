# 第 8 轮 · STAMP：把任务分解成图，把场景分解成物体，把路径分解成安全走廊

> 检索/复核日期：2026-10-24（UTC）。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「路径规划」「任务分解」「语义分割」。我先各自钉到本轮核实到的官方事实与 2026 年证据上，再合成主判断：**官方评分步骤给出了任务分解的骨架，但它不是线性序列，而是带双手资源约束、可交换分支和可逆节点的部分序图；四路相机 + D435 位姿 + EE 位姿使“物体级 3D 语义场景图”第一次在 UniBot 上可落地；碰撞感知路径规划则补上 VLA 最缺的“安全走廊”先验。三者不应在线拼成 TAMP 系统（单模型/延迟/感知误差都不允许），而应作为离线教师，蒸馏进唯一 VLA checkpoint。** 这既承接第 7 轮 PILOT-GPR 的放置/步骤/恢复主线，又把“评分步骤图”从线性状态机升级为可执行的部分序任务图，把“放置锚点”升级为物体/部件/容器图，把“落点闭环”升级为逐节点谓词验证。

## 0. 本轮先核实：榜单“有数据”不等于“数据可信”

本轮 `r.jina.ai` 渲染 `leaderboard.html` 时出现了 `Ranking · Live`，`leaderboard_data.json` 也含 8 个模型 × 32 任务的 256 条 `task_metrics`；但静态页面仍写「即将发布/Coming Soon」，JSON 的 `generated_from` 仍是 `gen_leaderboard.py`，详情页视频仍写「测试视频占位」。因此我把它标为 **“样例级榜单”**：可用于提出结构假设，不能当作真实排名证据。其数字与用户所说“榜首 <30%”一致：

|---|---|---|---:|---:|---:|
| 1 | MolmoAct2 | DexHacker | 29.7% | 39.0 | 44.02s |
| 2 | WALL-OSS-0.5 | Generalist Robotics | 28.5% | 38.9 | 43.74s |

| 4 | Spirit-v1.5 | VLAGO | 25.9% | 34.4 | 45.19s |

规则侧是本轮最确定的硬事实（[S2][S3]）：**32 任务必须用同一个模型完成，禁止按任务混用多个模型；架构不限（VLA/World Model 均可）；每任务 10 次运行，5 类泛化各 2 次；单次限时 180s；排名按 32 任务总平均成功率，平局才看总平均步骤分，再平局看提交日期。** 另外有不计分的单任务调试通道。第 7 轮把“成功率 + 步骤分”并列为目标；本轮修正为 **成功率先行，步骤分是诊断与平局指标**——终局步骤仍是成功闸门，但不应为了步骤分牺牲成功率。

榜单暴露了三个结构性事实：

1. **头部差距很小，共同瓶颈很大。** 8 个模型全部落在 20.5–29.7%，逐任务取 8 模型最优的“oracle”也只有 34.0%，仅比榜首高 4.3pp。换更强底座/更大数据仍有空间，但“再训一个更大的 VLA”不是唯一解；瓶颈更像是任务结构、几何精度与验证，而不是单一模型容量。
2. **长尾非常具体。** 最难 8 项是 Plug In Ethernet 17.7%、Unlock 20.1%、Spell robot 21.8%、Organize Stationery 22.5%、Open Pill Bottle 22.7%、Hang Cup 23.0%、Pick Out Battery 23.3%、Zip Up 23.4%。它们分别对应细插拔、小件旋转、组合放置、窄容器收纳、螺纹/透明件、钩挂、杂乱避碰、形变闭合——不是同一种能力。
3. **时间预算充裕。** 8 个模型平均耗时 43.7–45.2s，远低于 180s；256 个 task-model 单元的“时长—成功率”相关约 0.003，没有“做得越久越容易失败”的证据。这意味着每任务 1–2 次验证/重试在预算内可行。

## 1. 三个灵感词，各自钉到证据上

### 1.1 任务分解：官方步骤是线性文本，执行却是部分序图

官方 `score_steps` 是“抓插排（30）→ 抓插头（30）→ 插入（40）”这样的线性文本，但 T10 的真实执行是：一只手必须先**持续握住插排**，另一只手抓插头，然后双手协同插入。T26 同样：一手握端口、一手抓网线，最后插入。T04/T06/T13/T15/T20/T21/T22/T25 的多物体放置顺序可以交换；T27/T19/T14/T17 的终局步骤会被人类备注**撤销**（叠好的碗被拿走、拉好的拉链被拉开、拧开的瓶盖被拧回、合上的笔盒被打开）。所以正确的抽象不是“32 条线性状态机”，而是 **带双手资源约束、可交换分支、可逆节点的部分序任务图（BPOG）**。

证据链也支持“层级/部分序”而不是“端到端一条动作序列”：H-WM 用逻辑世界模型 + 视觉世界模型做 TAMP，报告长程任务提升 >50%（[S16]）；LoHo-Manip 用任务管理 VLM 输出剩余计划与 2D 关键点 trace，执行器跟随 trace 并滚动重规划（[S17]）；Hi-VLA 的系统对比中最佳层级配置在长程任务上 67.1% vs 平坦策略 25.3%（[S20]）；LiLo-VLA 把“搬运/到达”和“物体交互”解耦，零样本长程任务 69% 仿真/85% 真机（[S19]）；Spirit-v1.5 则从数据侧证明“失败—重试—绕路”的多样轨迹比干净单一路径更能学出恢复（[S15]）。这些证据共同指向：**分解粒度、分支顺序、终止条件**比“再多一层网络”更关键。

### 1.2 语义分割：不是“分割图像”，是“把场景变成可查询的物体/部件/容器图”

UniBot 的硬任务几乎都要求区分“物体/部件/容器/状态”，而不是只找一个抓取点：T26 要区分网线、插头、端口；T11 要在电池与积木之间只抓电池；T14 要区分瓶盖与瓶身、判断螺纹是否咬合；T19 要区分拉链头与布料；T01 要区分杯柄与架子挂钩；T10 要区分插排孔位与插头铜片；T27 要区分碗沿与碗内；T07 要区分相框与支架。一个全局视觉 token 可能隐式编码这些，但它不提供**跨帧身份、3D 关系、可验证谓词**——而这正是长尾失败最需要的东西。

2026 年的 3D 语义分割/场景图证据已经足够成熟：T-FunS3D 做任务驱动的层级开放词表 3D 功能分割（[S25]）；Clutt3R-Seg 用稀疏视角 3D 实例分割做语言 grounding 抓取，在杂乱场景报告 2.2× AP（[S26]）；OpenSplatGraph/TrackGraph 把在线开放词表 3D 场景图做到实时（[S27][S28]）；ReKep 用关系关键点约束 + 层级优化做实时感知—动作，支持多阶段、双手、反应式（[S21]）；AffordVLA/A2A 则证明把可供性/分割先验蒸馏进 VLA 能显著提升放置与物体操作（[S22][S23]）。UniBot 数据恰好提供了落地条件：四路相机、`head_stereo_left/right` 已校正、`state_d435` 给 D435 相机 6D 位姿、EE 位姿有 base/torso 两套、夹爪有开度（[S9][S10]）。**度量 3D 不是送上门，但可行**：立体基线/内参未在 `meta/info.json` 中给出，需要标定；腕部相机外参也需手眼标定；透明/形变物体要退回 2.5D + 腕部特写。这个限制必须写进方案，而不是假装深度图现成。

### 1.3 路径规划：不是“生成一条轨迹”，是“给 VLA 一条安全走廊 + 可回退的接近段”

长尾任务的失败往往不是“不知道该去哪”，而是“拿着东西过不去/最后几厘米撞了/姿态不对”：T10/T26 的插入轴、T11 的电池与积木间隙、T27 的碗沿上方接近、T12 的锁孔/金属环、T01 的挂钩曲线、T19 的拉链沿线、T31 的窄笔袋口、T17 的文具盒窄口、T24 的移动传送带。VLA 的动作 chunk 局部平滑，但不保证全局无碰撞；一个显式几何规划器能提供“从当前 EE 到预抓/预放位姿”的安全走廊。

证据侧：cuRoboV2 用深度融合距离场做 GPU 运动生成，支持最多 48 DoF 人形，报告 30ms 级规划、负载下 99.7% 成功（[S24]）；ReKep 把关键点约束交给层级优化器，实现实时闭环与双手协同（[S21]）；LoHo-Manip 用 2D trace 把“计划”变成执行器可跟随的视觉先验（[S17]）；VISTA 用世界模型生成目标图，让 VLA 跟随，OOD 从 14% 提到 69%（[S18]）。这些方法共同说明：**路径/目标不应只是文本，而应是可投影、可验证、可重规划的几何量**。但同样不能在线跑完整 TAMP：延迟、感知误差、单模型审计都不允许。正确用法是**离线教师 + 在线蒸馏/安全过滤**。

## 2. 主判断：STAMP-GPR，而不是“在线 TAMP”

```text
官方 score_steps + 5 条复述 + human 备注
        │
        ▼
BPOG：部分序任务图（双手/可交换/可逆/时序）
        │  节点 = {动词, 物体/部件, 目标, 手, 前条件, 效果, 官方步骤}
        ▼
S3G：物体级 3D 语义场景图（mask + 3D pose + 关系 + 状态）
        │  节点 = 物体/部件/容器/表面；边 = on/in/near/aligned/holds
        ▼
CAPP：离线 cuRoboV2 生成安全走廊（transit/approach/retreat）
        │  标签 = EE waypoints + 2D 投影 + clearance + 碰撞代价
        ▼
TAFD：教师→动作特征蒸馏进唯一 VLA
        │  辅助头 = mask / depth / subgoal / waypoint / predicate / relation
        ▼
PVR：逐节点谓词验证 + 撤销重开 + 重试/微调/重抓
        │
        ▼
单一 checkpoint + 确定性调度/安全检查（合规、低延迟）
```

四个组件的关系不是“串行流水线”，而是“**离线教师生成结构化监督，在线一个模型同时预测动作与结构**”：

- **BPOG** 解决“先做什么、哪只手做、失败了回到哪”。
- **S3G** 解决“物体/部件/容器在哪、是什么关系、现在是什么状态”。
- **CAPP** 解决“怎么过去、从哪里接近、碰撞了怎么退”。
- **TAFD** 解决“单模型/低延迟下怎么把上面三者装进 VLA”。
- **PVR** 解决“做完没有、被撤销了没有、要不要重试”。

这与第 7 轮 PILOT-GPR 的差别是关键的：第 7 轮的 SSG 是**线性**评分步骤状态机，PGL 是**2D 锚点 + 6D 放置位姿**，SVL 是**终局落点闭环**；STAMP 把 SSG 升级为**部分序/双手/可逆图**，把 PGL 升级为**物体/部件级 3D 图**，把 SVL 升级为**逐节点谓词 + 撤销恢复**，并新增**碰撞感知路径蒸馏**。这不是推倒重来，而是把第 7 轮最有效的“评分结构 + 放置 + 闭环”三件事，换成更适合长尾任务的表示。

## 3. 为什么这比“再训一个更大的 VLA/世界模型”更值得押

- **头部已经占了“更大模型/更多数据”的生态位。** WALL-OSS-0.5 用 4B、100 万+轨迹、20+本体做大规模预训练（[S13]）；DreamZero 用 14B 视频扩散世界模型做 7Hz 闭环（[S14]）；MolmoAct2 用 3.3M 样本的具身推理底座 + 自适应深度 token（[S12]）。我们再用同一路线追，算力和数据都不占优。
- **头部也在证明“结构/几何”有效。** MolmoAct2 排第一，靠的正是深度 token 与动作推理；DreamZero 排第三，靠的是世界模型提供的物理动态；Spirit 排第四，靠的是多样/恢复数据。STAMP 选择的是他们尚未占满的交叉点：**显式任务图 + 物体级 3D + 安全路径**，且用蒸馏保持单模型/低延迟。
- **长尾任务需要的是“可验证的中间状态”，不是更长的动作序列。** 插网线、开锁、拧瓶盖、拉拉链、挂杯子这些任务，失败点都能用几何/关系谓词描述；一旦谓词可验证，重试和恢复就有明确触发条件。纯动作克隆没有这个接口。
- **时间预算允许“慢一点但更稳”。** 平均 44s vs 180s，给 PVR 留了 1–2 次重试空间；这比在每一步都追求更快更划算。

## 4. 与第 7 轮的关系（深化与修剪）

| 关系 | 内容 |

## 5. 风险与合规（先立后破）

- **单模型边界**：BPOG/S3G 融合/调度/安全检查都是确定性代码；SAM/cuRobo/LLM 只在离线当教师；在线唯一学习模型是含辅助头的 VLA checkpoint；检索库是数据不是模型。模型卡逐项披露。
- **榜单不可信**：`generated_from` + 视频占位说明数字可能是样例；只把“<30%、长尾具体、时间充裕”当假设，真实瓶颈用不计分调试槽验证。
- **3D 标定**：`meta/info.json` 没有深度图/相机内参；立体基线、D435 与 head stereo 的对应、腕部手眼都要标定。标定不过关就退回 2D 锚点 + 腕部特写，不硬上 3D。
- **透明/形变**：试管、药瓶、拉链、毛巾、笔袋不做完整物理；用 2.5D、分割、腕部图像和任务专用谓词，失败就回退。
- **蒸馏负迁移**：辅助头可能抢容量；用低权重、分层解冻、早停和无辅助头基线对照；硬任务不升就砍 CAPP/TAFD。
- **延迟**：单卡 6B + 4 相机 + 辅助头，目标 chunk 16–32、7–10Hz、p99 <150ms；不达标先砍 ICR/关系头，再砍 waypoint 头。
- **统计噪声**：32×10=320 trials，p≈0.3 时 SE≈2.6pp；+3pp 只有约 1.2 SE。用配对任务/bootstrap + 调试槽，不拿单次榜单波动当结论。
- **规则未明**：外部数据、调试槽次数、步骤分聚合公式、单模型审计细则仍未知；默认只用官方数据，外部数据开关 OFF。

## 6. 一句话押注

**在成功率优先、32 任务同一模型、5 轴泛化的约束下，最值得押注的是：把官方评分步骤升级为可逆的部分序任务图（BPOG），把四路相机升级为物体/部件级 3D 语义场景图（S3G），把搬运/接近段交给碰撞感知路径教师（CAPP），再用教师→动作特征蒸馏（TAFD）把三者压进唯一 VLA——它同时攻插网线、开锁、拼字、收纳、开瓶、挂杯、取电池、拉拉链这八类长尾失败，而不用在线堆第二个模型。**

# 第 8 轮产物区 · STAMP-GPR 技术报告（任务图 + 3D 语义场景图 + 碰撞感知路径 + 单模型蒸馏）

> 目标赛事：宇树科技 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署、官方远程真机 API 评测。检索/复核日期：**2026-10-24（UTC）**。本报告在第 7 轮 PILOT-GPR（终局放置 + 少样本上下文 + 产学研）基础上迭代；第 6 轮 FLEET 仍只作工程检查单。**本报告最重要的新判断：官方评分步骤是任务分解的骨架，但执行是带双手资源约束、可交换分支和可逆节点的部分序图；四路相机 + `state_d435` + EE 位姿使物体级 3D 语义场景图可落地；碰撞感知路径应作为离线教师蒸馏进唯一 VLA，而不是在线拼 TAMP。**

## 0. 产物摘要

### 0.1 一句话

**把官方 `score_steps` 编译成 BPOG（双手/可交换/可逆的部分序任务图），把四路相机 + D435 位姿 + EE 位姿变成 S3G（物体/部件/容器级 3D 语义场景图），用 cuRoboV2 离线生成 CAPP（碰撞感知安全走廊），再用 TAFD（教师→动作特征蒸馏）把 mask/depth/subgoal/waypoint/predicate 压进唯一 VLA checkpoint；在线只跑一个模型 + 确定性调度/安全检查，PVR 负责逐节点验证、撤销重开与重试。**

### 0.2 组件与是否进推理

| 组件 | 作用 | 在线？ | 学习？ | 单模型合规 |
|---|---|---|---|---|
| BPOG 部分序任务图 | 官方步骤 → 带 hand/pre/eff/reversible 的 DAG；调度当前节点 | 是 | 否（离线编译） | 确定性代码，不是模型 |

### 0.3 预期收益与证伪

### 1.2 规则：成功率先行，单模型，10 次/任务，180s

官方中文/英文手册（[S2][S3]）明确：

- 排名按 32 任务**总平均成功率**；平局看总平均步骤分；仍平局看提交日期。
- 有不计分的单任务调试通道（[S33]）。

### 1.5 API：观测/动作自由度足够，但只有单字符串语言

## 2. 失败诊断：长尾不是一种能力

### 2.1 八类失败与组件映射

| 失败类型 | 典型任务 | 机制 | STAMP 组件 |

| 目标/部件 grounding | T26、T11、T14、T19、T01 | 分不清网线/插头/端口、电池/积木、瓶盖/瓶身、拉链头/布料、杯柄/挂钩 | S3G + PGL 回退 |

| 窄缝/插入/旋转 | T10、T26、T14、T12、T31 | 接近轴、间隙、螺纹、钥匙/环、拉链 | CAPP + PVR |

| 验证/假完成 | 全部 | 以为完成了，实际掉了/没到位/被撤销 | PVR 谓词 + settle |

### 2.2 为什么“再训一个更大的 VLA”不够

- 头部已占“更大模型/更多数据/更强世界模型”的生态位：WALL-OSS-0.5 4B + 100 万+轨迹 + 20+本体（[S13]）；DreamZero 14B 视频扩散 + 7Hz（[S14]）；MolmoAct2 3.3M 样本具身推理 + 自适应深度 token（[S12]）。同一路线追，算力/数据不占优。
- oracle 只比榜首高 4.3pp：不是“缺一个全能模型”，而是“每个模型都缺同一些结构化能力”。
- 长尾失败可用几何/关系谓词描述；一旦谓词可验证，重试/恢复就有触发条件。纯动作克隆没有这个接口。
- 平均 44s vs 180s：允许“慢一点但更稳”，PVR 的预算成立。

### 2.3 为什么不是“在线 TAMP”

在线串 LLM + SAM + cuRobo + VLA 的问题：

1. **单模型审计**：规则虽未禁止工具，但按任务调用外部大模型/检测器容易被认定为多模型；风险不值得。
2. **延迟**：SAM + 6D pose + cuRobo + LLM 串联很难稳定在 7–10Hz；API 是远程实时交互。
3. **感知误差级联**：分割错 → 位姿错 → 规划错 → VLA 被错误目标带偏。
4. **数据利用率低**：33k 演示的价值在于离线监督；在线 TAMP 不需要这些标签，浪费了数据。

因此选择 **离线教师 + 在线蒸馏**：教师负责“生成结构化监督”，VLA 负责“在不确定性下执行”。

### 3.2 S3G：物体级 3D 语义场景图

> 证据：开放词表 3D 功能分割/实例分割/场景图（[S25][S26][S27][S28]）与可供性蒸馏（[S22][S23]）已证明“物体/部件级结构”对杂乱与放置有效。

**图 schema：**

```text
node = {
  id, class, part_of, mask_emb, pose_3d (SE3), extent (bbox/size),
  affordance (grasp/insert/hook/press/pull), material (rigid/soft/transparent),
  state (open/closed, inserted, stacked, held, occluded)
}
edge = {on, in, near, aligned_with, holds, occludes, supports, inside}
```

**离线构建：**

1. 标定：`state_d435` 给 D435 相机在 base 系的 6D 位姿；head stereo 已校正，但基线/内参需标定；腕部相机做手眼标定；桌面平面用演示统计拟合。
2. 分割：SAM2/Grounded-SAM（[S31]）产生物体/部件 mask；对硬任务加开放词表提示（cable、plug、port、cap、zipper pull、handle、rim、slot）。
3. 深度：优先立体匹配（rectified pair）；退化时用单目深度 + 桌面/EE 尺度校准；透明/形变物体用腕部特写与 2.5D。
4. 6D 位姿：刚体用 FoundationPose 类/关键点 PnP；容器用平面+法向；小件用多视图融合；用 `recomputed_ee_valid` 过滤不可靠 EE。
5. 关系：3D 包围盒/点云重叠/支撑面/接近方向；生成 on/in/near/aligned/holds 边。
6. 标签：把节点 mask/pose/关系/状态投影到 VLA 输入分辨率，作为辅助头监督。

**在线：**

- VLA 的 mask/depth/pose 辅助头预测每路视角的物体/部件 mask 与深度；确定性融合模块做多视图关联、3D 位姿与关系更新。
- 不需要在线 SAM；所有学习部分在同一 checkpoint。
- 若 mask/depth 置信度低：退回第 7 轮的 2D 锚点 + 腕部特写；不硬用 3D 图。

**为什么是物体级而不是像素级：**

- 跨帧身份：同一电池/网线/拉链头在遮挡后仍可追踪。
- 3D 关系：on/in/aligned 可直接做谓词与路径约束。
- 可验证：节点谓词对应官方步骤，成功/失败可判定。
- 抗背景/干扰物：物体中心 token 不被全局纹理支配（与 Retrieval-VLA/Clutt3R-Seg 的证据一致，[S26]）。

### 3.3 BPOG：双手部分序任务图

> 证据：层级/部分序任务分解在长程与双手任务上优于平坦策略（[S16][S17][S19][S20]）；Spirit-v1.5 的失败—重试数据进一步支持可逆/恢复节点（[S15]）。

**节点字段：**

```text
node = {
  id, official_step, verb, object, target, hand (L/R/both/any),
  pre: [predicates], eff: [predicates], resources: [object/hand],
  reversible: bool, time_window: optional, weight: official_score
}
```

**边：**

- `precedence`：A 完成后 B 的 pre 才可能为真。
- `join`：T10/T26 的“插入”需要“握住插排/端口”和“抓住插头/网线”两个分支都完成。
- `resource`：同一只手不能同时做两个节点；同一物体被占用时不能重复抓。
- `time_window`：T24 的传送带目标必须在窗口内抓/放。

**调度：**

```text
ready = [n for n in graph if all(pre(n)) and resources_free(n)]
choose = argmax(weight(n) * urgency(n) / cost(n))   # 官方顺序先验 + 当前不确定性
execute(choose); update(S3G); verify(predicates)
if predicate_true_to_false(n): reopen(n) and descendants
```

**为什么这是“任务分解”而不是“任务提示”：**

- 图是离线编译的，不在线让 LLM 自由分解；避免第二个模型与不确定性。
- 节点与官方评分步骤对齐，PVR 的谓词直接对应得分点。
- 部分序允许交换/并行，减少不必要的长程依赖；可逆节点支持人类撤销。
- 失败时回到“可执行的 frontier”，而不是从头重来。

**回退：** 若图与当前观测冲突（例如物体被移走、任务文本未见），退化为官方线性顺序 + VLA 子目标头；不阻塞主流程。

### 3.4 CAPP：碰撞感知路径教师

**离线：**

- 用 S3G 点云/TSDF 构建场景；cuRoboV2 规划双臂 + 躯干的 transit/approach/retreat（[S24]）。
- 每个节点生成：
  - EE 6D waypoints（base 系）与时间戳；
  - 2D 投影（head/wrist）与 clearance；
  - 碰撞代价/最小间距；
  - 失败样本（碰撞/不可达）作为负例。
- 插入/闭合类任务（T10/T26/T14/T12/T19/T31）额外标注接近轴、预插入位姿、允许的横向误差；堆叠类（T27/T20/T01）标注上方接近与释放高度。

**在线：**

- VLA 预测 waypoint token/heatmap 与 action chunk；确定性 safety filter 用预测深度/S3G 做几何碰撞检查。
- 不安全：先尝试沿安全方向回退/抬高；仍不安全则用缓存的教师路径片段；不调用在线 cuRobo。
- 插入：VLA 预测接近轴 + 小范围螺旋/柔顺搜索；PVR 验证插入深度/接触。
- 双手：BPOG 分配 hand；safety filter 检查两臂自碰撞与共享工作空间。

**为什么蒸馏而不是在线规划：**

- 30ms 级规划器在离线批量生成时很便宜，但在线还要依赖准确点云/位姿；感知一错，规划就错。
- VLA 可以在感知不确定时用动作先验兜底；安全过滤器只做保守否决，不负责全局规划。
- 单模型/延迟/审计都更干净。

### 3.5 TAFD：教师→动作特征蒸馏

**唯一 checkpoint：**

```text
WLA-1.0-Base (6B, LoRA, [S29]) + action expert
  ├─ action head（flow matching / chunk）
  ├─ mask head（物体/部件，SAM 教师）
  ├─ depth head（立体/单目教师）
  ├─ subgoal head（BPOG 节点分类/进度）
  ├─ waypoint head（EE 路径 heatmap/token，cuRobo 教师）
  ├─ predicate head（节点谓词/关系/稳定）
  └─ relation head（on/in/near/aligned，可选）
```

**蒸馏目标：**

- mask：Dice + BCE，只对任务相关物体/部件加权（背景/桌面低权重）。
- depth：尺度不变/排序损失；用立体伪标签 + 桌面/EE 尺度校准。
- subgoal：当前节点 CE/BCE；用官方步骤 + 演示相位对齐生成标签。
- waypoint：2D heatmap BCE + 3D 偏移 L1；只在高置信教师路径上训练。
- predicate：节点完成/接触/稳定/包含 BCE；用演示与 human 备注生成正负例。
- relation：on/in/near/aligned 的 BCE/对比损失；用 S3G 教师。
- action：基座 flow matching + 少量教师路径条件下的动作蒸馏（KL/回归）。

**为什么不会变成“多模型”：**

- 所有头共享同一个 backbone/checkpoint；推理一次前向出所有输出。
- 教师（SAM/cuRobo/LLM）只在离线产生标签，不进入提交服务。
- BPOG/S3G 融合/调度/安全过滤是确定性代码，不是学习模型。
- 无 per-task LoRA、无任务路由、无模型集成。

### 3.6 PVR：逐节点谓词验证与恢复

```python
def run_node(node, graph, state, budget=2):
    for attempt in range(budget + 1):
        tokens = encode(node, state)
        for chunk in vla.stream(obs, tokens, chunk=16):
            action, aux = chunk
            if not safety_ok(action, aux, state):
                action = safe_fallback(node, state)
            execute(action)
            state = update_s3g(state, obs, aux)
            if predicate_true(node, state):
                break
        if predicate_true(node, state):
            settle_and_verify(node, state)      # 缓放/静置/稳定性
            if stable(node, state):
                return True
        if repairable(node, state):
            node = nudge_or_realign(node)
        else:
            node = regrasp(node)
    return False
```

- `predicate_true`：S3G 关系 + VLA predicate head + 事件（接触/静止/包含/插入深度）。
- `stable`：0.5s 窗口内物体相对位姿位移 <ε（ε 由演示统计）且谓词保持。
- 撤销：若已为真的谓词变成假（human 拿走/拉开/拧回/打开），`reopen(node)`，更新 S3G，重新调度。
- 预算：普通任务 ≤2 次；长程（T16/T17/T31）≤1 次；Endurance Governor 兜底总时长。
- 误判防护：双阈值（几何位移 + 谓词）+ 腕部特写确认；不确定时选择保守重试而不是假完成。

### 4.1 离线教师流水线

```python
for task in tasks:
    graph = compile_bpog(task.score_steps, task.human_notes)
    for episode in sample(task.demos, n=200):
        frames = keyframes(episode, graph)          # 每节点 3–5 帧 + 1fps
        masks  = sam2_grounded(frames, task.prompts)
        depth  = stereo_depth(frames.head_stereo)   # 或 mono + 尺度校准
        scene  = fuse(masks, depth, episode.state_d435, episode.ee_poses)
        for node in graph.nodes:

```

- 采样不是全量 33k：每个任务抽 150–300 条，硬任务多抽；每 episode 只取关键帧（接触/释放/插入/闭合/撤销），控制标注成本。
- 伪标签 QA：mask 面积/时序一致性；depth 与桌面/EE 尺度一致性；waypoint 可达/无碰撞；predicate 与官方步骤对齐。
- 人工抽检 10%；不达标的任务退回 2D/终局闭环，不阻塞全量。

### 4.2 辅助标签

| 标签 | 来源 | 用途 | 失败回退 |
|---|---|---|---|
| 物体/部件 mask | SAM2/Grounded-SAM | S3G 节点、mask 头 | 2D 锚点 |
| 深度/点云 | 立体匹配 + `state_d435` | 3D 位姿、碰撞 | 单目+尺度 |
| 6D 位姿 | FoundationPose/关键点 PnP | S3G pose、OPT | 2D 跟踪 |
| 节点相位 | 官方步骤 + 演示动作/接触 | subgoal 头、BPOG 对齐 | 线性顺序 |
| EE waypoints | cuRoboV2 | waypoint 头、安全走廊 | VLA 动作 |
| 谓词/关系 | 演示 + human 备注 | PVR、relation 头 | 规则谓词 |
| 撤销事件 | human 备注 + 合成 | 可逆图、恢复 | 通用扰动 |

### 4.3 损失

```text
L = L_action
  + λ1 L_mask + λ2 L_depth + λ3 L_subgoal
  + λ4 L_waypoint + λ5 L_pred + λ6 L_relation
  + λ7 L_distill
```

| 项 | 含义 | 起始权重 |
|---|---|---:|
| L_action | 基座 flow matching / chunk | 1.0 |
| L_mask | Dice + BCE（任务物体加权） | 0.10 |
| L_depth | 尺度不变/排序 + 局部 L1 | 0.10 |
| L_subgoal | 当前节点 CE/BCE | 0.20 |
| L_waypoint | 2D heatmap BCE + 3D 偏移 | 0.10 |
| L_pred | 节点谓词/稳定/包含 BCE | 0.20 |
| L_relation | on/in/near/aligned BCE/对比 | 0.05 |
| L_distill | 教师路径/图 token 的 KL/回归 | 0.10 |

**训练技巧：**

- 辅助头先冻结 backbone 训 1–2 epoch，再解冻 LoRA；避免早期辅助损失破坏动作先验。
- 硬任务过采样 2–3×，但不做 per-task 模型；用 loss 权重/采样器。
- 教师标签置信度加权；低置信样本不进 waypoint/predicate 损失。
- 训练时注入 S3G 噪声/遮挡/位姿扰动，让 VLA 学会在感知不确定下执行；推理时才不会“看到完美图”。
- 保留无辅助头基线，严格消融；辅助头不升就砍。

### 4.5 算力与人力

- 离线标注：8×H100 80GB；SAM/深度/位姿 32 任务 ×200 条 ×关键帧，约 2–4 天；cuRobo 批量约 1 天。
- 训练：6B backbone LoRA + 辅助头，8×H100 约 2–3 周（含消融）；单卡 24GB 可走 4-bit/小批量调试，但全量建议 80GB。
- 推理：单张 A100/H100；bf16/FP8；4 相机 480×640；chunk 16–32；目标 7–10Hz，p99 <150ms/chunk。
- 人力：1 感知/3D、1 VLA 训练、1 机器人/规划、1 任务本体/评测；4 人最小。
- 数据：官方 33k 足够；外部实验室数据只作可选多样性，默认 OFF。

### 4.6 标定与数据风险

- `state_d435` 是 D435 相机位姿，但 `head_stereo_left/right` 是否就是该 D435 立体对、基线/内参是多少，`meta/info.json` 未给出；必须用标定板/已知几何/演示 EE 回放标定。标定不过关 → 退回 2D 锚点。
- 腕部相机外参未给出；用 EE 位姿 + 手眼标定；透明/反光件用腕部特写与多帧融合。
- `recomputed_ee_valid` 为 0 的帧要过滤；夹爪 5.5–0.0 开→闭，谓词要用开度阈值。
- 没有深度图；立体匹配在透明/弱纹理/反光上会失败；用单目+桌面尺度/EE 尺度兜底，并在模型卡标注。

## 6. 创新点清单（持续迭代；动机/差异/可行性/资源/步骤/风险/状态）

> 状态：**押注**=本轮主线；**升级**=旧点被改造；**保留**=沿用；**降级**=保留但不再是主回路；**砍**=不做；**可选**=时间允许才做。

### I1 BPOG 双手部分序任务图（押注｜升级第 7 轮 SSG）
- 动机：官方评分步骤是线性文本，但 T10/T26 是双手 join、T04/T22 等顺序可交换、T27/T19/T14/T17 可被撤销；线性状态机无法表达。
- 差异：节点带 hand/pre/eff/resources/reversible/time_window；边有 precedence/join/resource；调度器按可执行 frontier 选择，而不是固定顺序。
- 可行性：32 个任务可手工编译；官方步骤+human 备注+演示相位足够；不需要新数据。
- 资源：1 名任务本体/工程师 ×2 周；CPU；无额外算力。
- 步骤：解析 steps → 编译 DAG → 标注 pre/eff/hand/reversible → 对齐演示相位 → 接调度器/PVR。
- 风险：手工图错；谓词噪声；过度约束。缓解：先线性回退；每任务 10 条演示抽检；图不匹配时退回官方顺序。

### I2 S3G 物体级 3D 语义场景图（押注｜升级 PGL）
- 动机：长尾要区分物体/部件/容器/状态，2D 锚点没有跨帧身份和 3D 关系。
- 差异：节点含 mask/pose/extent/affordance/material/state；边含 on/in/near/aligned/holds；在线由同一 VLA 的 mask/depth/pose 头融合。
- 可行性：四路相机 + `state_d435` + EE 位姿；离线 SAM/深度/6D pose 教师；3D 关系可用几何规则。
- 资源：8×H100 2–4 天标注；1 名感知/3D ×3 周；FoundationPose/SAM 许可逐个核。
- 步骤：标定 → 分割/深度 → 6D pose → 图融合 → 标签 → 蒸馏。
- 风险：透明/形变/遮挡；立体基线未知。缓解：2.5D+腕部；低置信回退 2D；标定不过关不做 3D。

### I3 CAPP 碰撞感知路径教师（押注｜新增）
- 动机：插入/杂乱/堆叠/挂钩的失败多在“过不去/最后几厘米撞了”。
- 差异：离线 cuRoboV2 生成安全走廊，蒸馏为 waypoint token/heatmap；在线只做几何安全过滤，不跑规划器。
- 可行性：cuRoboV2 支持人形/双臂；S3G 点云可建 TSDF；30ms 级批量规划。
- 资源：1 名机器人/规划 ×2 周；8×H100 1 天；cuRobo 许可核对。
- 步骤：场景 TSDF → 节点规划 → 标签/负例 → waypoint 头 → safety filter。
- 风险：感知误差/教师不可达/蒸馏失真。缓解：只在高置信场景训练；安全过滤保守否决；不可达节点回退 VLA 动作。

### I4 TAFD 教师→动作特征蒸馏（押注｜新增）
- 动机：单模型/低延迟/审计不允许在线串 SAM/cuRobo/LLM；33k 数据的价值在离线监督。
- 差异：一个 6B checkpoint 多头输出 action/mask/depth/subgoal/waypoint/predicate；教师只离线。
- 可行性：WLA-1.0-Base + LoRA + 轻量头；标准蒸馏/多任务训练；单卡可推理。
- 资源：8×H100 2–3 周；1 名 VLA 工程师；教师模型许可。
- 步骤：加头 → 阶段 1 标签训练 → 阶段 2 蒸馏 → 阶段 3 闭环 → 量化部署。
- 风险：辅助头抢容量/负迁移/延迟。缓解：低权重、分层解冻、早停、无辅助头基线；不达标就砍头。

### I5 OPT 物体系放置位姿迁移（保留｜升级）
- 动机：放置仍是终局闸门；K 条演示的相对位姿统计可跨场景迁移。
- 差异：容器系从 2D 锚点升级为 S3G 物体 6D 位姿；离散度驱动直接执行/伺服/退化。
- 可行性：EE base 位姿 + S3G pose；零梯度；可缓存。
- 资源：1 周；无需重训。
- 步骤：H_i 库 → 在线物体系 → K 条检索 → 中位数/离散度 → 执行/伺服/回退。
- 风险：透明/小件位姿误差。缓解：分桶回退 ICR/2D 锚点；τ_task 自动估。

### I6 PVR 逐节点谓词验证与恢复（升级｜SVL+NRB）
- 动机：成功=所有节点为真；人类会撤销；假完成是最贵的失败。
- 差异：从终局闭环升级为逐节点谓词；撤销触发 reopen；nudge/regrasp/retry 预算。
- 可行性：S3G 关系 + predicate head + 规则；180s 预算足够 1–2 次。
- 资源：1 周；演示含自然重试片段。
- 步骤：谓词定义 → 标签 → 稳定性检测 → 重试/恢复 → 时长守卫。
- 风险：误判/耗时。缓解：双阈值+腕部确认；长程限 1 次；超时回退。

### I7 ICR 上下文检索（降级｜保留）
- 动机：33k 演示是现成少样本库；对 OOD/背景/位置有帮助。
- 差异：键改为 S3G 物体关系 + BPOG 相位；不再用全局外观。
- 可行性：缓存编码 + HNSW；延迟可控。
- 资源：1–2 周；8×H100 1–2 天编码。
- 步骤：切段 → 键 → 缓存 → 训练注入 → 压测。
- 风险：延迟/透明任务键失效。缓解：K≤4、降维/预取；不达标关掉。

### I8 SSG 官方步骤解析/指令映射（保留｜并入 BPOG）
- 动机：32×5=160 条复述；官方步骤是评分骨架。
- 差异：从线性图解析器升级为 BPOG 的输入层；字符串匹配 + 嵌入兜底。
- 可行性：已抓全 32 任务；纯确定性。
- 资源：3 天。
- 步骤：解析 info.json/tasks.parquet → 规范化 → 映射 → 兜底。
- 风险：未见复述/中文指令。缓解：VLA 语言编码 + 子目标头；不依赖精确匹配。

### I9 GPR-VLA/WLA 主干（保留）
- 动机：单一 checkpoint 承接动作+辅助头；Apache-2.0、可微调。
- 差异：不变；新增多头与图 token 接口。
- 可行性：WLA-1.0-Base 6B + LoRA/action expert 已在 HF/代码栈可用；多头为标准结构。
- 资源：8×H100 2–3 周；1 名 VLA 工程师。
- 步骤：加载底座 → 加 action/辅助头 → 分阶段训练 → 量化/编译。
- 风险：6B 容量/延迟。缓解：LoRA/量化/蒸馏；必要时换更小底座。

### I10 TLE/ACP/GF 数据引擎（保留｜修剪）
- 动机：真实锚定的反事实仍是最便宜的轴数据。
- 差异：只服务 BPOG/S3G/CAPP 的标签与硬任务过采样；不做全 32 任务高保真孪生。
- 可行性：TLE/ACP/GF 已有实现；只跑硬任务/关键帧，成本可控。
- 资源：1 人 ×2 周；8×H100 2–3 天生成/QA。
- 步骤：选硬任务 → 生成位置/背景/干扰反事实 → QA → 真实混采 → GF 加权。
- 风险：合成负迁移。缓解：GF 软权重 + 真实混采；硬任务不升就关。

### I11 治理/部署（保留）
- 动机：180s、单模型审计、远程 API 稳定性是硬约束；部署不能拖研究后腿。
- 差异：把第 6 轮 FLEET 降为工程检查单；DebugLoop 作为发布门，而不是研究轴。
- 可行性：官方 profile 有调试模式；N 端口/状态隔离/健康检查是标准工程。
- 资源：1 人 ×1 周；少量真机调试时段。
- 步骤：端口隔离 → 4h soak → 模型卡/审计 → 调试槽 → 计分跑。
- 风险：调试槽稀缺/规则变化。缓解：每版本最多 1 槽；离线相对比较兜底。

### I12 L2L 实验室数据（降级｜可选）
- 动机：背景/位置多样性。
- 差异：从“数据农场”降为“合规的可选补充”；默认 OFF。
- 可行性：高校 G1 实验室与 LeRobot 采集栈已公开；按官方 schema 对齐。
- 资源：3 实验室 ×2 任务 ×100–200 条；2 人协调。
- 步骤：协议 → 试点 1 实验室 → QA → 合规开关 → 并入（仅当允许）。
- 风险：规则未明/硬件异构。缓解：邮件确认；只采刚体/容器任务；不并入主实验。

### I13 TCLB 孪生评测（降级）
- 动机：需要低成本的失败挖掘/相对比较。
- 差异：只做离线相对比较；不再承诺真机校准主回路。
- 可行性：第 5 轮已有 2.5D 编辑/回放管线；不追求全物理。
- 资源：沿用既有；1 人 ×1 周维护。
- 步骤：固定评测集 → 回放/2.5D 变体 → 失败聚类 → 指导硬任务。
- 风险：仿真—真机偏差。缓解：只做相对排序，不做绝对结论。

### I14 在线 TAMP/LLM/SAM/cuRobo 串联（砍）
- 动机：曾考虑用在线 TAMP 直接生成计划。
- 差异：与离线蒸馏路线相反；在线多模型串联。
- 可行性：技术上可行，但延迟/感知级联/审计风险高。
- 资源：若做需额外 2–3 人月与多模型服务；不投入。
- 步骤：不执行；教师只离线。
- 风险：单模型审计不过、p99 超标、错误级联；因此砍。

### I15 Latent state world model 头（可选｜低优先）
- 动机：DreamZero 证明世界模型对泛化有效；但 14B 视频扩散太重。
- 差异：只预测物体状态/谓词/下一帧 latent，不生成视频；作为 PVR 的辅助。
- 可行性：加一个轻量 dynamics 头；用演示下一状态监督。
- 资源：1–2 周；1 名 VLA 工程师；风险：分散主线。
- 步骤：加 dynamics 头 → 下一状态/谓词监督 → 与 PVR 联动 → 消融。
- 风险：分散主线/增益不明确。缓解：只在 E4 后有余力才做；不进主路径。

### 已砍清单（跨轮）
- 在线 LLM/TAMP/SAM/cuRobo 串联；全 32 任务高保真孪生；自由仿真数据；运行时仿真/MPC；仿真 RL；布料/拉链/透明全物理；每任务 LoRA/模型合并；14B 视频世界模型主路径；为步骤分牺牲成功率的奖励塑形。
