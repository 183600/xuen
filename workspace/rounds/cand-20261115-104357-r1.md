# 第 5 轮（灵感循环新周期第 1 轮；本轮灵感：「续航能力」×「跌倒恢复」）

> **基线**：第 4 轮 InstructGauge-WR（IP-328–333；定义 448–467；引理 59–62；实验 E457–E472）。第 3 轮 InstructGauge、第 2 轮 ToolGauge、第 1 轮 LeanGauge / MODGAUGE 继续继承。
> 本轮纪律：**安全地板优先 + 增量增强 + 严格退化**。续航与跌倒恢复只允许在既有安全包线内重新分配能量与动作，不允许扩大物理可行域；任一环节不可用都必须逐级退回 v4。

## 0. 直觉与动机

**灵感 1（续航能力 → 不是「还能跑多久」，而是「还能安全地恢复到什么程度」）**

直觉：多数系统把电量当成一个标量「剩余运行时间」，然后在任务层做吞吐优化。但对一台已经带有契约、漂移界和不可逆屏障的机器人，这个看法是危险的。电量下降不只是「时间变少」，它会**改变被控对象本身**：电压跌落让可用力矩与角速度上限收缩；供电不足让相机帧率、通信频率和推理预算下降；持续大电流让温度上升、内阻增大、模型不确定性变大。于是低电量并不是「同一个系统少了一点燃料」，而是「一个能力更小、证据更旧、模型更不准的系统」。因此能量必须进入安全契约的**参数**，而不是只进入目标函数的**代价**。

第二个直觉是：能量必须被切成「任务预算」和「恢复储备」两部分，且恢复储备**不可挪用**。人类登山不会把保命的水用来冲顶；机器人也不应把「站起来/退回安全姿态」所需的能量花在多做一次探测上。更精细地说，恢复储备不应该是固定百分比，而应是**状态相关**的：在平地跌倒和在楼梯边缘跌倒，恢复代价完全不同。正确的量是 `ρ(x)`——从状态 `x` 出发、在能量与功率约束下完成一次有界恢复所需的最小代价。更进一步，电池可能「焦耳够、功率不够」：总能量足以慢慢站起来，但恢复动作的峰值功率会触发电压塌陷，使执行器饱和，反而站不起来。所以恢复储备至少是二维的：**能量储备 + 功率储备**。

第三个直觉是：续航优化有道德风险。更激进的步态、更高的速度、更少的验证，确实能降低每米能耗、提高名义续航，但也会把系统推到可恢复性边界附近，增加跌倒概率和恢复代价。若直接优化期望运行时间，最优策略会系统性地「借」恢复储备。因此本轮把「续航」改造成**认证续航**：在预注册场景集上、在可恢复性不变式成立的前提下，给出一个带覆盖保证的运行时间下界；优化只允许在这个可行域内部进行。

**灵感 2（跌倒恢复 → 跌倒不是终止，而是一个有契约的模式）**

直觉：对足式机器人，「永不跌倒」既不可证也不现实；真正可设计的安全性质是**可恢复性**：从每一个你允许自己进入的状态出发，都存在一次能量有界、功率可行、时间有界的恢复；如果恢复不可行，则至少存在一个受控跌倒，使损伤有界。这正是 viability kernel / control barrier function 的语言：不是把所有坏事都排除，而是保证系统永远留在「还有退路」的集合里。

第二个直觉是：跌倒检测必须是**最高优先级的异步中断**，而不是任务循环里的一个分支。一个跌倒事件会瞬间让当前动作分块的全部证据过期；如果还继续执行块内后续动作，就是把「证据陈旧窗口」从 K 步放大成「跌倒后的 K 步」。因此跌倒必须能在一个控制周期内抢占在途块，并且块必须是前缀封闭的，才能安全截断到跌倒前最后一条已执行动作。恢复动作本身也不是免费的：它可能带来高力矩冲击、自碰撞、脆弱传感器触地、瞬时大电流。恢复需要自己的契约、自己的失败分类、自己的能量预算。

第三个直觉是：储备必须覆盖**跌倒之后**的状态，而不是跌倒之前。人从桌上跌落，最坏的不是「掉下去」这一下，而是落地姿态让后续起身变得不可能。因此预跌倒状态下的恢复储备应取所有可能跌倒后继状态上的上确界；这虽然保守，但它是硬安全，而不是平均安全。受控跌倒则是最后的合法退路：当恢复确实不可行时，选择让冲击速度、关节峰值力矩、传感器触地概率和质心落差综合损伤最小的姿态，而不是「什么都不做地摔下去」。

**灵感 3（两者耦合 → 低电量跌倒是一个乘性级联，不是两个独立故障）**

直觉：能量与跌倒至少双向耦合。低电量会削弱执行器、降低传感频率、增大模型误差，从而提高跌倒概率；而恢复动作是瞬时高功率事件，会进一步拉低电压，可能造成执行器饱和，导致**恢复过程中的第二次跌倒**。反过来，续航优化会压缩安全裕度、提高跌倒风险；恢复储备又会占用任务能量、降低续航。二者不是「两个独立故障率相加」，而是「一个故障让另一个故障更致命」的乘性级联。

最危险的链条是：低电量 → 跌倒 → 恢复耗尽储备 → 恢复中途失败 → 二次跌倒/不可恢复。要在结构上阻断它，不能只靠更好的跌倒分类器，而要靠三条硬约束的联合：**恢复储备覆盖跌倒后继状态**、**可恢复性不变式在每个动作前缀上成立**、**跌倒事件立即中断在途块**。这三条分别对应能量侧、状态侧和时间侧；缺一条，级联就会从缺口里漏过去。

## 1. 研究问题（本轮要回答什么）

- **Q1（续航的可认证性）**：能否把「续航」从期望运行时间改造成带覆盖保证的下界？在电压跌落、温度、老化与传感降额下，如何定义可信的能量下界与单调收缩的能力包线，并让旧契约在能量变化时**过期**而不是继续被信任？
- **Q2（可恢复性的最小结构）**：保证「从每个允许状态都有一次有界恢复」所需的最小结构是什么？恢复代价 `ρ`、峰值功率 `P_rec`、可恢复集与屏障函数如何在线计算，且不把任务性能压到不可用？
- **Q3（耦合级联的阻断）**：如何分配「跌倒鲁棒」的恢复储备与块长，使低电量跌倒不会演化成恢复中途失败？续航与可恢复性之间的 Pareto 前沿如何量化，认证续航的保守性如何被实验证伪？

## 2. 三条设计原则（雏形，正式化见产物区定义 468–480）

**P1 恢复储备不可挪用（Non-fungible recovery reserve）**

能量被显式切成任务预算与恢复储备；恢复储备是状态相关、跌倒鲁棒、且同时覆盖能量与峰值功率的硬约束，任务规划器无权借用。形式化方向：`e_t ≥ ρ_fall(x_t) + δ_E` 且 `P_avail(e_t) ≥ P_fall(x_t) + δ_P`，其中 `ρ_fall`、`P_fall` 取所有可能跌倒后继状态上的上确界。若储备不足，系统只能降级任务或进入受控退避，不能继续消耗。

**P2 可恢复性不变式（Recoverability invariant）**

只执行那些「任意前缀执行后仍留在可恢复集内」的动作或块；用一个联合屏障 `h_rec = min(h_E, h_P)` 做在线否决。形式化方向：候选块 `C` 可执行当且仅当 `∀ j ≤ K`，在最坏情形动力学与保守能量模型下 `h_rec(x_j, e_j) ≥ 0`。屏障只做**否决**，不做授权；它属于 shield，不属于 objective。能量下降时能力包线单调收缩，绝不允许「低电量反而解锁新动作」。

**P3 跌倒即中断 + 受控退化（Fall-as-interrupt + protected fall）**

跌倒事件是最高优先级中断，必须在一个控制周期内抢占在途块；依靠第 3 轮的前缀封闭分块，把块安全截断到跌倒前最后一条已执行动作。若恢复契约不存在或储备不足，则进入受控跌倒模式，以有界损伤为目标；若连受控跌倒都不可行，则进入合规/松弛模式并显式报告 `Unrecoverable`，而不是假装仍可恢复。优先级固定为：跌倒中断 ≻ 可恢复性屏障 ≻ 能量储备 ≻ CVC ≻ 任务。

## 3. 与基线的接口（如何退化）

- 能量估计器不可用 ⇒ 使用保守的固定储备比例与最坏情形降额，退回 v4 的固定参数；
- 恢复代价模型不可用 ⇒ 使用全局最坏恢复储备与固定块长阈值，只保留「储备不可挪用」这一条硬约束；
- 跌倒监测不可用 ⇒ 取消跌倒中断，但必须把块长压到 1、速度限幅、只允许在平坦地形执行，退化到保守 v4；
- 可恢复性屏障不可用 ⇒ 在近跌倒风险区强制 `K=1` 并降速；
- 所有新组件失效 ⇒ InstructGauge-WR v4 ⇒ InstructGauge v3 ⇒ ToolGauge ⇒ LeanGauge ⇒ MODGAUGE 原样。

## 4. 预期贡献

1. 一个**能量条件化的安全契约**：用带覆盖保证的能量下界与单调降额包线，把「低电量」从运行时间问题变成契约有效性问题；
2. 一个**跌倒鲁棒的恢复储备**：同时约束总能量与峰值功率，并把储备定义在跌倒后继状态上，避免「焦耳够、功率不够」的假恢复；
3. 一个**联合能量—可恢复性不变式**与跌倒中断分块执行器：把低电量跌倒的乘性级联压回「可检测、可截断、可退化」的线性结构；
4. 一条完整可证伪路径：E473–E490 覆盖能量下界覆盖、降额有效性、恢复代价校准、跌倒中断、认证续航、级联阻断、sim-to-real 与 50Hz 时序保全。

## 5. 本轮最大风险

**一句话**：可恢复性证书的覆盖率、恢复代价与峰值功率模型都只在预注册的跌倒模式、地形与电池老化范围内校准；真实长尾跌倒会让 `ρ_fall` 与 `P_fall` 同时低估，而续航优化会主动把系统推到「刚好够恢复」的边界，使模型误差恰好集中在最不能出错的地方——「储备看似充足，恢复却在中途失败」。

## 2. 形式化定义

**定义 468（能量状态与认证下界）**

设电池状态 `b_t = (soc_t, V_t, T_t, R_t, age_t)`。认证能量下界定义为

```text
E_t^- = max(0, (soc_t^- · Q_nom − Q_loss(T_t, age_t)) · η(V_min, T_t) − κ_e σ_t)
P_t^- = V_min · I_max(T_t, e_t)
```

其中 `soc_t^-` 是水平 `1-α_e` 的单侧下置信界，`Q_loss` 是不可逆容量损失，`η` 是在最低期望电压下的放电效率，`σ_t` 是估计不确定度，`κ_e` 是覆盖因子。要求

```text
P(E_t^true ≥ E_t^-) ≥ 1 − α_e
```

`E_t^-` 不是「电量计读数」，而是「在给定置信水平下仍可安全支配的能量」。同理 `P_t^-` 是可用峰值功率下界。定义硬地板 `E_floor`（BMS 截止 + 安全余量）与任务可用能量 `E_t^use = E_t^- − E_floor`。

**定义 469（能量条件可采纳集与单调降额）**

```text
A_e = { a ∈ A_0 :
        τ_req(a,x) ≤ τ_max(V_min(e), T)
      ∧ q̇_req(a,x) ≤ q̇_max(V_min(e), T)
      ∧ P_req(a,x) ≤ P_t^-
      ∧ f_sensor(a) ≥ f_min(e) }
```

要求单调性：

```text
e_1 ≥ e_2  ⇒  A_{e_1} ⊇ A_{e_2}
```

即能量只能让能力包线**收缩**，不能让低电量解锁高能量时被禁止的动作。对既有 CVC 契约 `κ`，定义能量有效性：

```text
Valid(κ, e) ⇔ actions(κ) ⊆ A_e
             ∧ pre/post(κ) 在降额模型 M_e 下仍成立
```

若不成立，则 `Expired(κ, e)`：旧契约必须重新实例化，而不是继续被信任。这一点把「低电量」从运行时间问题提升为**契约有效性问题**。

**定义 470（恢复代价、峰值功率与跌倒鲁棒储备）**

对跌倒后的状态 `x_f`，定义最小恢复能量代价与最小恢复峰值功率：

```text
ρ(x_f) = min_{π_rec, T ≤ T_rec} ∫_0^T c_e(x_u, u) du
s.t.  x_0 = x_f,  x_T ∈ S_safe,  x_u ∈ X_safe,
      u ∈ A_{e(u)},  contact-safe(u)

P_rec(x_f) = min_{π_rec 可行} max_{u ∈ π_rec} P_req(u)
```

`ρ^+_α(x_f)` 是 `ρ(x_f)` 的单侧上置信界，覆盖率 `1-α_r`，按跌倒模式 `φ ∈ Φ` 与地形类别分层校准。若不存在可行恢复，则 `ρ(x_f) = ∞`，`P_rec(x_f) = ∞`。

预跌倒状态下的储备必须覆盖跌倒后继，而不是只覆盖跌倒前：

```text
ρ_fall(x) = sup_{x_f ∈ FallSucc(x)} ρ^+_α(x_f)
P_fall(x) = sup_{x_f ∈ FallSucc(x)} P_rec(x_f)
```

若 `FallSucc(x)` 未被模型覆盖，则使用全局最坏值并把该状态标记为 `unmodeled`；`unmodeled` 状态只允许在 `K=1` 与限速模式下执行。这个 `sup` 是保守的，但它是硬安全所需要的；后续可用风险预算把它放松为分层分位数，但不能在硬保证路径上放松。

**定义 471（能量/功率屏障与联合可恢复性屏障）**

```text
h_E(x,e) = e − ρ_fall(x) − δ_E
h_P(x,e) = P_t^- − P_fall(x) − δ_P
h_rec(x,e) = min(h_E(x,e), h_P(x,e))
```

`δ_E`、`δ_P` 覆盖未被共形界捕获的模型误差与估计误差。要求不变式

```text
h_E(x,e) ≥ 0  ∧  h_P(x,e) ≥ 0
```

直观：`h_E` 保证「总焦耳够恢复」，`h_P` 保证「瞬时功率够恢复且不触发电压塌陷」。仅有 `h_E` 不够——这是本轮与「电量百分比」方案的关键区别。

**定义 472（联合可恢复—能量不变式）**

```text
I(x,e) ≡ x ∈ X_safe
        ∧ e ≥ E_floor
        ∧ h_E(x,e) ≥ 0
        ∧ h_P(x,e) ≥ 0
```

`X_safe` 继承 v4 的运动学、碰撞、支撑多边形与关节限制。VitaGauge-ER 只允许在 `I` 成立的状态上执行任务动作；`I` 是硬约束，不是软惩罚。

**定义 473（跌倒事件与跌倒分类）**

跌倒事件在 `t_f` 触发，当且仅当多源信号满足

```text
F(y_t) = 1 ⇔
    (|roll| > θ_r ∧ roll_rate · sign(roll) > ε_r)
  ∨ h_base < h_min
  ∨ support_polygon_lost
  ∨ (∃ 关节饱和 ∧ |a_base| > a_max)
```

跌倒模式集合

```text
Φ = { SLIP, TRIP, SUPPORT_LOSS, ACT_SAT,
      ENERGY_COLLAPSE, EXTERNAL_PUSH, SENSOR_FAULT }
```

每种模式 `φ` 对应一个恢复策略族 `Π_φ` 与一个恢复代价先验。分类不是最终目的，目的是让 `ρ^+` 与 `P_rec` 能按模式分层校准；分类错误会直接表现为 E475 的校准误差，而不是被静默吸收。

**定义 474（跌倒恢复契约）**

```text
RecoverContract(x_f, e_f) =
    (φ, π_rec, T_rec, ρ^+_α, P_rec, S_target, pre, post)
```

约束：

```text
π_rec ∈ Π_φ
∀u ∈ π_rec: u ∈ A_{e(u)}
energy(π_rec) ≤ e_f − E_floor
P_rec(x_f) ≤ P_avail(e_f)
x_T ∈ S_safe ∪ S_pf
contact-safe: 无自碰撞、无脆弱传感器触地、无关节限位违背
```

若不存在满足上述约束的契约，返回 `⊥`，并转入受控跌倒规划。恢复契约必须作为 `RecoverCert` 记录，不能只存在于控制器的隐式状态里。

**定义 475（受控跌倒）**

```text
π_pf = argmin_π E[D(x_T)]
s.t. x_T ∈ S_pf,  u ∈ A_e,  T ≤ T_pf

D = w_1 v_impact² + w_2 τ_peak²
  + w_3 1[sensor_contact] + w_4 Δh_CoM
```

`S_pf` 是静态稳定、低质心、非脆弱接触的姿态集合。若 `S_pf` 不可达，则进入合规/松弛模式（降低关节刚度、限制电流、保护传感器），并输出 `Unrecoverable` 证书。受控跌倒不是设计失败，而是「恢复不可行」时的合法安全动作；把它显式建模，才能避免系统在不可恢复时继续执行任务块。

**定义 476（能量感知块长）**

```text
δ_vis(e) = L_vis / f_min(e) + ε_proc
K_vis(e) = floor(δ_max / δ_vis(e))

K_energy(x,e) = max { K :
    Σ_{j=1}^K ĉ_e(x_j, a_j) + ρ_fall(x_K) + δ_E ≤ e }

K_rec(x,e) = max { K :
    ∀ j ≤ K,  h_rec(x_j, e_j) ≥ 0 }

K*(x,e) = min(K_task, K_irrev, K_vis(e), K_rec(x,e), K_energy(x,e))
```

其中 `ĉ_e` 是最坏情形单步能量成本，`ρ_fall(x_K)` 是块结束后的恢复储备——块长预算必须为「执行完这一块之后还能恢复」付费，而不是只为块本身的能耗付费。若 `K* < 1`，不生成块，转入恢复/重规划。`K_vis(e)` 把「低电量导致传感降频」直接翻译成证据陈旧窗口，从而与第 3 轮的块长理论接上。

**定义 477（跌倒中断执行语义）**

优先级固定为

```text
跌倒中断  ≻  可恢复性屏障  ≻  能量储备  ≻  CVC  ≻  任务
```

执行语义：

```text
Execute(C, x, e):
  for j = 1..K:
    t_j = now()
    if FallMonitor.fired(t_j):
      return Trunc(C, j−1), FallCert(t_j, φ, x_j, e_j, j−1)
    if h_rec(x_j, e_j) < 0:
      return Trunc(C, j−1), RecoverCert(x_j, e_j)
    if not Valid(CVC_j, e_j):
      return Trunc(C, j−1), ExpiredCert(CVC_j, e_j)
    apply(a_j)
  return C, OkCert(...)
```

跌倒事件使在途块**整体失效**；只保留已经执行并通过门控的前缀 `C_{1:j−1}`。这依赖第 3 轮的前缀封闭性：若块不是前缀封闭的，`Trunc` 不一定是合法程序，跌倒中断就会变成「截断到一半的非法动作序列」。

**定义 478（认证续航）**

```text
T_end^cert(π; β) = min_{s ∈ S_eval} T_end(π, s)
```

`S_eval` 是预注册场景集（地形、负载、温度、电池老化、跌倒模式）的分层共形校准集，覆盖率 `≥ 1-β`；`T_end(π,s)` 是首次违反 `I` 或任务失败的时刻。若始终不违反，则取任务时域。定义「续航剖面」为映射

```text
(task, terrain) ↦ T_end^cert
```

而不是单一数字。认证续航是下界，不是期望值；它回答的是「在多大把握下，系统至少能安全运行这么久」，而不是「平均能跑多久」。

**定义 479（三类证书）**

```text
EnergyCert_t  = (E_t^-, P_t^-, σ_t, A_e, validity_horizon)
RecoverCert_t = (x_t, φ, ρ_fall, P_fall, π_rec, h_E, h_P)
FallCert      = (t_f, φ, x_f, e_f, executed_prefix,
                 π_used, outcome, residual_margin)
```

三类证书通过 ROS 消息发布（继承 IP-329 的 `CVC_Spec`，新增可选字段 `energy_cert`、`recover_cert`、`fall_cert`）。字段缺省时等价于 v4；字段存在时，订阅方可独立重放「能量是否够恢复、跌倒是否被及时中断」的判断。

**定义 480（VitaGauge-ER 主闭环）**

```text
ER-9C = G → H → E → D → C → R → X → V → U
```

其中 `G` 接地、`H` 假设生成、`E` 能量证书、`D` 降额、`C` 分块规划、`R` 可恢复性过滤、`X` 带跌倒中断的执行、`V` 验证、`U` 更新。相对 v4 的 WRC-7C，新增的是 `E→D` 与 `R`、`X` 中的中断语义；主路径频率与既有 CVC 接口保持不变。

```python
# IP-334 EnergyGauge
class EnergyGauge:
    def __init__(self, bms, model, alpha_e=0.05, kappa_e=2.0):
        self.bms = bms
        self.model = model
        self.alpha_e = alpha_e
        self.kappa_e = kappa_e

    def certified_bounds(self):
        soc_lo = self.bms.soc_lower_quantile(self.alpha_e)
        temp = self.bms.temperature()
        age = self.bms.age()
        v_min = self.model.expected_min_voltage(soc_lo, temp)
        q_loss = self.model.irreversible_capacity_loss(age, temp)
        eta = self.model.discharge_efficiency(v_min, temp)
        sigma = self.bms.soc_uncertainty()
        e_lo = max(0.0, (soc_lo * self.model.q_nom - q_loss) * eta
                   - self.kappa_e * sigma)
        p_lo = v_min * self.model.current_limit(temp, e_lo)
        return e_lo, p_lo

    def derating_envelope(self, e_lo, p_lo):
        return ActionEnvelope(
            tau_max=self.model.torque_limit(e_lo),
            qdot_max=self.model.velocity_limit(e_lo),
            p_max=p_lo,
            f_sensor=self.model.sensor_rate(e_lo),
        )

# IP-335 RecoveryReserve
class RecoveryReserve:
    def __init__(self, recovery_value, power_model, fall_successors, delta_e, delta_p):
        self.value = recovery_value        # ρ^+ 的保守值函数/回归器
        self.power = power_model           # P_rec 的保守模型
        self.successors = fall_successors  # x -> FallSucc(x)
        self.delta_e = delta_e
        self.delta_p = delta_p

    def fall_robust_reserve(self, x):
        succ = self.successors(x)
        if not succ.covered:
            return float("inf"), float("inf"), "unmodeled"
        rho = max(self.value.upper_bound(xf) for xf in succ)
        p_rec = max(self.power.min_peak(xf) for xf in succ)
        return rho, p_rec, "ok"

    def barriers(self, x, e_lo, p_lo):
        rho, p_rec, status = self.fall_robust_reserve(x)
        h_e = e_lo - rho - self.delta_e
        h_p = p_lo - p_rec - self.delta_p
        return h_e, h_p, min(h_e, h_p), status

# IP-336 ViabilityShield
class ViabilityShield:
    def __init__(self, reserve, dynamics, margin):
        self.reserve = reserve
        self.dyn = dynamics
        self.margin = margin

    def admissible(self, x, e_lo, p_lo, a):
        x1 = self.dyn.step(x, a)
        e1 = e_lo - self.dyn.energy_cost(x, a)
        p1 = self.dyn.available_power(x, e1)
        h_e, h_p, h, _ = self.reserve.barriers(x1, e1, p1)
        return h >= self.margin

    def filter_chunk(self, C, x, e_lo, p_lo):
        for j, a in enumerate(C.actions):
            if not self.admissible(x, e_lo, p_lo, a):
                return C.truncate(j), "recoverability"
            x = self.dyn.step(x, a)
            e_lo = e_lo - self.dyn.energy_cost(x, a)
            p_lo = self.dyn.available_power(x, e_lo)
        return C, "ok"

# IP-337 FallMonitor
class FallMonitor:
    def __init__(self, imu, contacts, kinematics, thresholds):
        self.imu, self.contacts = imu, contacts
        self.kin = kinematics
        self.th = thresholds

    def fired(self):
        roll, roll_rate = self.imu.roll(), self.imu.roll_rate()
        if abs(roll) > self.th.roll and roll * roll_rate > self.th.roll_rate:
            return True, "SLIP_OR_TRIP"
        if self.kin.base_height() < self.th.h_min:
            return True, "SUPPORT_LOSS"
        if self.contacts.support_polygon_lost():
            return True, "SUPPORT_LOSS"
        if self.kin.actuator_saturated() and \
           abs(self.imu.base_accel()) > self.th.a_max:
            return True, "ACT_SAT"
        return False, None

# IP-338 EnergyAwareChunker
def plan_chunk_er(M, iota, H, x, e_lo, p_lo):
    k_task = M.iac.max_task_chunk(iota, H)
    k_irrev = M.irrev_barrier.max_chunk(iota)          # 跨不可逆动作时为 1
    k_vis = M.energy.freshness_chunk(e_lo)             # 低电量 -> 传感降频 -> 块更短
    k_rec = M.viability.max_feasible_horizon(x, e_lo, p_lo)
    k_energy = M.energy.max_energy_horizon(x, e_lo, iota)
    K = min(k_task, k_irrev, k_vis, k_rec, k_energy)
    if K < 1:
        return None
    return M.iac.plan_chunk(iota, H, K=K)

# IP-339 ProtectedFall
class ProtectedFall:
    def __init__(self, damage_model, safe_postures):
        self.damage = damage_model
        self.safe_postures = safe_postures

    def plan(self, x, e_lo, p_lo):
        candidates = self.safe_postures.reachable(x, e_lo, p_lo)
        if not candidates:
            return None, "Unrecoverable"
        best = min(candidates, key=lambda s: self.damage.expected(s))
        return best, "protected_fall"

# IP-340 VitaGauge-ER 主闭环
def vitagauge_er(M, s, ell=None):
    e_lo, p_lo = M.energy.certified_bounds()
    env = M.energy.derating_envelope(e_lo, p_lo)

    iota = M.nlib.ground(ell, M.scene, M.ontology) if ell else M.default_iota
    H = M.lbox.hypothesize(s, M.dbox.R[s], iota)
    C = plan_chunk_er(M, iota, H, M.state, e_lo, p_lo)
    if C is None:
        return enter_recovery_or_replan(M, e_lo, p_lo)

    C, why = M.viability.filter_chunk(C, M.state, e_lo, p_lo)
    if not C.actions:
        return enter_recovery_or_replan(M, e_lo, p_lo)

    for j, a in enumerate(C.actions):
        fired, phi = M.fall.fired()
        if fired:
            return enter_recovery(M, M.state, e_lo, p_lo,
                                  fall_phi=phi, executed_prefix=j)
        if not M.cvc.joint_pre(a):
            return replan_from(M.state)
        h_e, h_p, h, status = M.reserve.barriers(M.state, e_lo, p_lo)
        if h < 0 or status == "unmodeled":
            return enter_recovery(M, M.state, e_lo, p_lo,
                                  fall_phi=None, executed_prefix=j)
        if not M.energy.contract_valid(M.cvc.current_spec(), e_lo):
            return replan_from(M.state)
        M.env.apply(a)
        e_lo, p_lo = M.energy.update_after(a)

    return C, M.energy.certificate(), M.reserve.certificate()

def enter_recovery(M, x, e_lo, p_lo, fall_phi=None, executed_prefix=None):
    contract = M.recovery.plan_contract(x, e_lo, p_lo, phi=fall_phi)
    if contract is not None:
        return execute_recovery(M, contract)
    plan, why = M.protected_fall.plan(x, e_lo, p_lo)
    if plan is not None:
        return execute_protected_fall(M, plan)
    return enter_compliance_mode(M, why)   # 显式 Unrecoverable
```

## 4. 推导

**引理 63（恢复储备的充分性）**
假设 A1：恢复模型保守，即 `ρ^+_α(x_f) ≥ ρ(x_f)` 且 `P_rec(x_f) ≥ max_u P_req(u)`；A2：`FallSucc(x)` 覆盖从 `x` 出发所有可能的跌倒后继。若 `I(x,e)` 成立，则对任意 `x_f ∈ FallSucc(x)`，都存在一个恢复契约，其总能量不超过 `e − E_floor`、峰值功率不超过 `P_t^-`。

证明：由 `h_E ≥ 0` 得 `e − E_floor ≥ ρ_fall(x) + δ_E ≥ ρ^+_α(x_f) ≥ ρ(x_f)`；由 `h_P ≥ 0` 得 `P_t^- ≥ P_fall(x) + δ_P ≥ P_rec(x_f)`。于是 `x_f` 满足定义 474 的能量与功率约束；再由 `ρ`、`P_rec` 的定义，存在相应的恢复轨迹与峰值功率不超界的策略，故恢复契约存在。证毕。

**引理 64（能量降额的单调性）**
若 `e_1 ≥ e_2`，则 `A_{e_1} ⊇ A_{e_2}`；因此不存在「在较高能量时被禁止、在较低能量时被允许」的动作。

证明：`τ_max`、`q̇_max`、`P_t^-`、`f_min` 均为能量参数的单调函数（能量越高，上限越大/频率越高），`A_e` 是这些上界的交集；交集随上界放宽而扩大。故包含关系成立。证毕。

推论：只要控制器始终使用 `A_e` 并对旧契约重新验证，能量下降不能扩张物理可行域，只能使契约过期。这把「低电量」限制在「降级」而不是「变形」。

**引理 65（跌倒中断的前缀安全性）**
假设候选块 `C` 前缀封闭，跌倒监测延迟 `Δ ≤ 一个控制周期`，且状态估计在 `t_f` 前有效。则跌倒前执行的前缀 `C_{1:j−1}` 是合法程序，`Trunc(C,j−1)` 也是合法程序；进一步，若跌倒前 `I` 成立且 A1–A2 成立，则跌倒后的恢复在能量与功率上可行。

证明：前缀封闭性保证任意前缀 `C_{1:j−1}` 都是合法程序，故截断不会产生非法动作序列。监测器在下一个动作前触发，故最后执行的是 `j−1`；`Trunc` 返回的正是该前缀。恢复可行性由引理 63 应用于跌倒后继状态得到。证毕。

注意：这条引理只保证「能量/功率可行」与「动作序列合法」，不保证「恢复一定成功」；恢复成功率取决于恢复策略在真实地形/接触上的泛化，这是 E476/E485 要测的量。

**引理 66（联合不变式阻断低电量—跌倒级联）**
若跌倒前 `I` 对所有时刻成立，且 A1–A2 成立，则恢复过程不会耗尽硬地板，也不会因功率不足触发电压塌陷，从而不会产生「恢复诱导的二次跌倒」中的能量/功率型级联。

证明：由引理 63，恢复契约的能耗 `≤ ρ_fall(x)`、峰值功率 `≤ P_fall(x)`。执行后剩余能量至少为 `E_floor + δ_E`，功率裕度至少为 `δ_P`；恢复动作仍落在 `A_e` 内，故不会因功率不足造成执行器饱和。证毕。

这条引理是「结构性阻断」而非「概率性缓解」：它把级联的必要条件（恢复时能量/功率不足）直接变成不可能，除非模型假设 A1/A2 被破坏。

**引理 67（严格退化等价性）**
令 `E_t^- = ∞`、`A_e = A_0`、`ρ_fall = P_fall = 0`、`FallMonitor = ∅`、`K_energy = K_rec = ∞`，则 VitaGauge-ER 主闭环逐字退化为 InstructGauge-WR v4。若只关闭恢复模块而保留能量模块，则得到「能量降额的 v4」；若只关闭能量模块而保留恢复模块，则得到「v4 + 恢复屏障」。证明：逐项代入定义 468–477，所有新增门控变为恒真或空操作，`ER-9C` 退化为 `WRC-7C`。证毕。

**引理 68（认证续航的覆盖保证）**
若 `S_eval` 是满足可交换性的 split-conformal 校准集，覆盖率 `1-β`，且 `T_end^cert = min_{s∈S_eval} T_end(π,s)`，则

```text
P(T_end^true ≥ T_end^cert) ≥ 1 − β
```

证明：`T_end` 是标量响应；取校准集上的最小值等价于取其 `(1-β)` 下分位数，标准 split-conformal 下界给出该覆盖保证。证毕。

限制：可交换性在部署分布漂移（新地形、电池老化、负载变化）下不成立；因此必须按地形/老化/跌倒模式分层校准，并在 E473/E481 中报告**每层**覆盖率，而不是只报告全局平均值。

**命题 1（续航—可恢复性前沿的存在性与非单调性）**
在策略族连续、`T_end(π,s)` 与 `min_t h_rec` 连续且有界的条件下，可达的 `(T_end, min_t h_rec)` 集合是紧集，故 Pareto 前沿存在。更重要的是，认证续航最优解一般**不是**无约束续航最优解：存在环境使更激进的策略降低每米能耗却提高 `ρ_fall`，从而在某个点之后只能靠借恢复储备来继续提升名义续航。因此 `T_end^cert` 通常严格小于名义续航，且差额随地形复杂度与电池老化增大。

论证：这是约束优化 `max T_end s.t. I(x,e) ∀t` 的标准结论；非单调性由「激进策略降低能量速率但提高恢复代价」的构造给出。该命题的可证伪形式是 E481/E484：如果 `T_end^cert` 与名义续航的差额不随地形复杂度增加，说明 `ρ_fall` 没有捕捉到恢复难度的变化。

| 组件 | 域 | 时间 | 空间 | 正确性锚 |

## 7. 本轮最大风险

**一句话**：可恢复性证书的覆盖率、恢复代价与峰值功率模型都只在预注册的跌倒模式、地形与电池老化范围内校准；真实长尾跌倒会让 `ρ_fall` 与 `P_fall` 同时低估，而续航优化会主动把系统推到「刚好够恢复」的边界，使模型误差恰好集中在最不能出错的地方——形成「储备看似充足、恢复却在中途失败」的虚假安全。
