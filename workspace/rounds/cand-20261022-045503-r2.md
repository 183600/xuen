# 想法区 · 第 2 轮

**灵感词**：dependency analysis / upper bound / Monte Carlo tree search  
**起点**：第 1 轮没有留下实质设计（只有 heartbeat），所以本轮从零建立 v0.1；不推翻任何旧结论，只把接口留好。

## 直觉：三个词各自解决什么

- **dependency analysis**：DAG 的 head/tail 给出每个任务的最早开始时间与「做完它之后还必须走多长」；关键链是天然下界，ready set 是天然合法动作集。
- **upper bound**：任何完整表调度都是一个可行解，因而给出 OPT 的上界；临界路径优先的表调度还有 Graham 的 `2 - 1/m` 最坏情况保证。上界同时是剪枝阈值：下界已经不小于当前上界的分支不可能改进。
- **Monte Carlo tree search**：在「选哪个 ready 任务、放到哪台机器」的序贯决策上做 anytime 搜索；rollout 不断产生新的可行上界，UCT 把预算分配给更有希望的分支。

三者真正咬合的地方不是「MCTS 里顺便算个界」，而是维护一个**双侧证书**：

```text
L  ≤  OPT  ≤  U
```

`L` 来自依赖分析（下界），`U` 来自已找到的可行调度（上界），MCTS 只探索 `LB < U` 的区域；当 `L` 追上 `U` 时，当前调度被证明最优。

## 候选方案：DUB-MCTS

- 状态：`σ = (S, A, c)`，`S` 已调度任务集，`A` 各机器可用时间，`c` 各任务完成时间。
- 动作：选择一个 ready 任务 `i` 和一台机器 `k`，在 `max(A_k, 前驱完成时间)` 开始。显式保留机器选择，允许「主动空闲」，这样搜索空间覆盖最优解（仅有「最早机器」会丢解）。
- 下界：`max(关键路径下界, 工作量注水下界, 前沿下界)`。
- 上界：CP 优先表调度作为初始 incumbent；每次 rollout 的完整调度更新 incumbent。
- 搜索：UCT（按 makespan 取小）+ 未访问动作优先 + 每 K 轮强制前沿扩展，保证认证模式下的穷尽性；`LB ≥ U` 的分支安全剪掉。
- 输出：incumbent 调度、区间 `[L,U]`、相对间隙；`L = U` 或前沿为空时给出最优性证书。

## 本轮要验证的命题

1. 依赖下界是可采纳的，剪枝不会删掉严格更优解。
2. `(任务, 机器)` 动作空间 + 最早可行开始，覆盖至少一个最优调度。
3. CP 初始上界确实可行，并继承 Graham 的 `2 - 1/m` 保证。
4. 小实例上 DUB-MCTS 能达到精确最优；较大实例上能缩小「根下界」间隙。
5. 关键疑问：在确定性调度上，MCTS 的统计引导是否真的优于同预算随机重启？初步原型的答案是「略优但不稳定」，这被列为本轮最大风险之一。

## 下一轮增量方向

- 把「前沿下界」`L_F` 工程化，替换静态根下界作为证书。
- 加入 energetic reasoning / edge-finding 等下界，专门处理强资源竞争。
- 在 PSPLIB 风格与无依赖 partition 难例上做消融，和 CP-SAT/精确搜索对照。
- 再考虑随机工时：把状态转移改成 chance node，并重新定义期望上界与剪枝。

## 1. 问题与动机

### 1.1 形式化问题

考虑经典的**同构并行机、带优先约束的最小化最大完工时间**问题：

```text
P | prec | Cmax
```

给定：

- 任务集合 `V = {1, ..., n}`；
- 处理时间 `p_i ∈ Z_{≥1}`；
- 优先约束 `E ⊆ V × V`，`(i, j) ∈ E` 表示 `i` 必须在 `j` 开始前完成；`(V, E)` 是无环图（DAG）；
- 机器数 `m ∈ Z_{≥1}`，机器同构。

一个调度由开始时间 `s_i ∈ Z_{≥0}` 与机器分配 `μ_i ∈ {1, ..., m}` 组成，满足：

```text
(i, j) ∈ E        ⇒  s_j ≥ s_i + p_i
μ_i = μ_j         ⇒  [s_i, s_i + p_i) 与 [s_j, s_j + p_j) 不重叠
```

目标：

```text
Cmax(s) = max_i (s_i + p_i)  →  min
```

记最优值为 `OPT`。

假设 `p_i > 0` 且时间取整数。零工时任务可在预处理中收缩；连续时间需要对下界的严格剪枝做 epsilon 处理，本文不展开。

### 1.2 为什么选这个问题

三个灵感词在这个问题上有自然的、非拼贴的分工：

- **dependency analysis**：DAG 的 head/tail 直接给出关键链下界；ready set 直接给出合法动作；前驱完成时间直接决定状态转移。
- **upper bound**：任何一个完整表调度都是可行解，因此都是 `OPT` 的上界；CP 优先表调度还有 Graham 的 `2 - 1/m` 最坏情况保证。上界同时是剪枝阈值。
- **Monte Carlo tree search**：调度是序贯决策；MCTS 天然 anytime，适合「预算受限、需要随时给出可行解和误差界」的场景。

### 1.3 与已有做法的区别

- 纯表调度（CP/LPT）快，但只有近似保证，不能证明最优。
- 纯分支定界（B&B）能证明最优，但下界弱时树爆炸，且没有「先给一个好解」的 anytime 行为。
- 纯 MCTS 能 anytime，但确定性优化中 rollout 噪声大，且没有最优性证书。

DUB-MCTS 把 B&B 的**双侧证书**与 MCTS 的**预算分配**结合：MCTS 负责找好解，依赖下界负责剪枝和证书，incumbent 负责给出可行上界。

## 3. 依赖分析

### 3.1 静态 head/tail

按拓扑序计算 head：

```text
r_i = max(0, max_{j ∈ pred(i)} (r_j + p_j))
```

按逆拓扑序计算 tail：

```text
q_i = max(0, max_{j ∈ succ(i)} (p_j + q_j))
```

关键路径长度：

```text
L_CP = max_i (r_i + p_i)
```

`L_CP` 是 `OPT` 的下界：任何调度都必须沿某条依赖链依次执行，链长不超过 `Cmax`。

工作量下界：

```text
L_W = ceil( (Σ_i p_i) / m )
```

根下界：

```text
L_0 = max(L_CP, L_W) ≤ OPT
```

### 3.2 动态 earliest start

在状态 `σ` 中，对每个未调度任务 `i` 定义**乐观最早开始时间**：

```text
es_i(σ) = max(
    min_k A_k,
    max_{j ∈ pred(i), j ∈ S} c_j,
    max_{j ∈ pred(i), j ∈ R} (es_j(σ) + p_j)
)
```

解释：

- `min_k A_k`：至少有一台机器在此刻之后可用；
- 已调度的前驱必须完成；
- 未调度的前驱必须先执行完，按乐观的 `es_j + p_j` 估计。

`es_i` 忽略了机器争用，因此是乐观的；`es_i + p_i` 是 `i` 完成时间的下界。

### 3.3 关键链作为证书

取使 `r_i + p_i` 最大的任务 `i*`，沿前驱回溯即可得到一条关键链。它有两用途：

- 作为 `L_CP` 的**可解释证书**：若 `U = L_CP`，直接证明最优。
- 作为动作先验：优先调度 tail 大的 ready 任务，通常能更早压缩关键链。

注意：关键链不是唯一的；动态 `es_i` 可能在状态深处给出比静态 `L_0` 更紧的局部信息。

## 4. 搜索状态、动作与覆盖性

### 4.1 状态

搜索状态定义为：

```text
σ = (S, A, c)
```

其中：

- `S ⊆ V` 是已调度任务集合，且对优先约束**向下封闭**：若 `i ∈ S` 且 `j → i`，则 `j ∈ S`；
- `A = (A_1, ..., A_m)`，`A_k` 是机器 `k` 的下一次可用时间；
- `c_i` 是 `i ∈ S` 的完成时间。

派生量：

```text
C(σ) = max_k A_k          （已调度任务的最晚完成时间）
R(σ) = V \ S
W(σ) = Σ_{i∈R} p_i
Ready(σ) = { i ∈ R : pred(i) ⊆ S }
```

### 4.2 动作

一个动作是二元组 `a = (i, k)`：

- `i ∈ Ready(σ)`；
- `k ∈ {1, ..., m}` 是选择的机器。

转移：

```text
t = max( A_k, max_{j ∈ pred(i)} c_j )
S' = S ∪ {i}
A'_k = t + p_i
A'_l = A_l        (l ≠ k)
c'_i = t + p_i
```

记 `σ' = T(σ, (i, k))`。

关键点：动作显式包含机器选择，且允许 `t > min_l A_l`，也就是允许**主动空闲**。这不是多余的：固定任务顺序时，把任务放到较晚可用的机器上，可能给后续长任务留下更早的机器，从而得到更短的 makespan。

### 4.3 覆盖性命题

**命题 1（动作空间覆盖最优）**：对任意可行调度 `S = (s, μ)`，存在从根状态出发的动作序列，其诱导调度 `S'` 满足 `Cmax(S') ≤ Cmax(S)`。因此搜索树中至少有一个最优叶子。

**证明草图**：

1. 将 `S` 中的任务按开始时间 `s_i` 非降序排列（`p_i > 0` 保证前驱严格早于后继；同开始时间只可能出现在不同机器上）。
2. 按此顺序，对每个任务 `i` 执行动作 `(i, μ_i)`，即使用它在原调度中的机器。
3. 对位置归纳：所有已处理任务在 `S'` 中的开始时间和完成时间都不晚于原调度。于是轮到 `i` 时，机器 `μ_i` 在 `S'` 中的可用时间不晚于 `s_i`，且 `i` 的所有前驱都已完成且完成时间不晚于 `s_i`。
4. 因此转移给出的 `t ≤ s_i`；归纳成立，最终 `Cmax(S') ≤ Cmax(S)`。证毕。

这个命题说明：搜索空间虽然只考虑「非延迟 + 允许主动空闲」的调度，但不会漏掉最优值。若只允许「最早可用机器」，命题不成立；这是必须显式保留机器维度的原因。

### 4.4 动作去重

机器同构，因此：

- 若 `A_k = A_l`，动作 `(i, k)` 与 `(i, l)` 产生同构状态，只保留一个；
- 若两个动作产生完全相同的 `(S', sorted(A'), c')`，只保留一个；
- 可选的更强支配：同一 `S'` 下，若状态 `σ_1` 的机器可用时间向量与「仍被剩余任务依赖的完成时间」逐分量不大于 `σ_2`，则 `σ_2` 可删。v0.1 只实现前两条，第三条留作接口。

## 5. 双侧界

### 5.1 状态下界 `LB(σ)`

定义三个分量：

**(a) 已完成部分**

```text
LB_done(σ) = C(σ) = max_k A_k
```

已调度任务必须全部完成，故最终 makespan 不小于它。

**(b) 关键路径下界**

```text
LB_CP(σ) = max( C(σ), max_{i∈R} (es_i(σ) + p_i) )
```

其中 `es_i` 由 3.2 节定义。它忽略机器争用，因此是下界。

**(c) 工作量注水下界**

把 `A` 升序排列为 `b_1 ≤ ... ≤ b_m`。定义

```text
T* = min { T ∈ Z : Σ_{k=1}^m max(0, T - b_k) ≥ W(σ) }
LB_W(σ) = T*
```

含义：即使允许抢占、忽略优先约束，从当前机器可用时间出发，处理完剩余 `W(σ)` 工作量也至少要到 `T*`。优先约束只会让它更晚，所以 `T*` 是下界。

`T*` 可用二分查找计算：`T ∈ [max_k A_k, max_k A_k + W(σ)]`，容量函数单调。

**总下界**：

```text
LB(σ) = max( LB_done(σ), LB_CP(σ), LB_W(σ) )
```

**引理 1（下界可采纳）**：对任意从 `σ` 出发的完整调度，其 `Cmax ≥ LB(σ)`。

**证明**：

- `LB_done`：已调度任务的最大完成时间不可能倒退。
- `LB_CP`：对剩余任务按拓扑序归纳。实际开始时间不小于 `min_k A_k`（此前无机器可用），不小于已调度前驱的完成时间，也不小于未调度前驱的实际完成时间；而 `es_i` 用乐观值替代实际值，故实际开始时间 ≥ `es_i`，实际完成时间 ≥ `es_i + p_i`。
- `LB_W`：到任意时刻 `T`，所有机器能提供的总加工时间至多 `Σ_k max(0, T - A_k)`；若小于 `W(σ)`，不可能完成全部剩余工作。抢占和忽略优先约束只会放宽限制，所以原问题同样不可能。证毕。

### 5.2 初始上界与 Graham 保证

用 CP 优先表调度构造初始 incumbent：

```text
π(i) = q_i          （tail 大者优先；平局取 p_i 大者）
```

每一步从 `Ready` 中取 `π` 最大的任务，放到当前最早可用的机器上，开始时间取「机器可用时间」与「前驱完成时间」的较大者。

得到可行调度 `π_0` 与 `U_0 = Cmax(π_0)`。

**事实（Graham 1979）**：对 `P | prec | Cmax`，任何表调度的 makespan 满足

```text
U_0 ≤ (2 - 1/m) · OPT
```

因此 v0.1 从第一秒起就有一个带最坏情况保证的可行解。实际实现还可以在根节点跑若干次随机表调度，取最优作为 `U_0`；这不破坏保证，只会更好。

### 5.3 前沿下界 `L_F`

仅有根下界 `L_0` 通常很松。搜索过程中可以把「未关闭的搜索位置」组织成一个割，得到更强的下界。

先定义节点的关闭状态：

- **terminal**：所有任务已调度，已评估其 makespan；
- **pruned**：`LB(σ_v) ≥ U`；
- **exhausted**：没有未尝试的、满足 `LB(child) < U` 的合法动作，且所有子节点都已关闭。

一个节点是 **open**，当且仅当它不是上述三种。

**前沿位置集合 `F`**：所有仍然 open、且至少还有一个未尝试且满足 `LB(child) < U` 的合法动作的节点。直观理解：把已关闭的子树全部剪掉，`F` 就是剩余搜索空间的「切口」。任何 makespan 小于当前 `U` 的调度，都不可能经过已关闭子树：

- terminal 子树的 makespan 已 ≥ `U`（否则 `U` 会被更新）；
- pruned 子树的所有完成都 ≥ `LB ≥ U`；
- exhausted 子树归纳地不含更优解。

因此它必然经过某个 open 节点；沿着它的路径继续往下，若当前 open 节点没有未尝试动作，就进入某个 open 子节点；最终要么到达一个有未尝试动作的 open 节点（属于 `F`），要么到达一个 terminal 叶子（其 makespan ≥ `U`，与「更优」矛盾）。所以它必然经过某个 `F` 中的节点。

定义：

```text
L_F = min_{x ∈ F} LB(σ_x)          （F 非空时）
```

> 实现备注：把 `F` 中的节点替换成「它尚未尝试的动作所对应的子状态」，可以得到更细的切口和更紧的 `L_F`；两者都是合法割。v0.1 采用节点级切口，优先保证实现与证明简单；动作级细化留到下一轮。

**引理 2（前沿下界）**：若存在 makespan 严格小于 `U` 的调度，则 `OPT ≥ L_F`；结合 `L_0`，有

```text
L = max(L_0, L_F) ≤ OPT
```

**证明**：取任意 `Cmax < U` 的可行调度，沿搜索树路径走。关闭子树不可能包含它；路径上第一个「仍 open 且有未尝试动作」的节点就落在 `x ∈ F`。该调度的 makespan ≥ `LB(σ_x)`（引理 1），所以 `OPT ≥ LB(σ_x) ≥ L_F`。若不存在更优调度，则 `U = OPT`，结论平凡成立。证毕。

**实现要点**：

- 用一个最小堆维护 `F` 中 open 节点及其 `LB`；
- 节点首次出现未尝试动作时加入 `F`；其未尝试动作耗尽或节点关闭时删除；
- 当 `U` 下降时，`LB ≥ U` 的节点可以永久删除（`U` 只减不增）；
- 为了不让下界因新节点插入而回退，维护单调版本 `L ← max(L, L_F)`。每个 `L_F` 都是合法下界，取历史最大值仍然合法。
- 若 `F` 为空，说明所有根到叶路径都已关闭，当前 `U` 就是 `OPT`。

`L_F` 是 v0.1 相对「只报根下界」的关键改进：搜索越深、关闭的分支越多，切口越靠下，下界通常越紧。

## 6. 算法 DUB-MCTS

### 6.1 主循环

```text
算法 DUB-MCTS(G, p, m, B, K)
────────────────────────────────────────────
1  (r, q, L_0) ← PRECOMPUTE(G, p, m)
2  π_0, U_0 ← CP-LIST-SCHEDULE(G, p, m)
3  best ← (U_0, π_0);  U ← U_0
4  root ← NEW-NODE(σ_0 = (∅, 0^m, ⊥))
5  root.lb ← LB(σ_0)
6  F ← {root}
7  L ← L_0
8  for t = 1, 2, ..., B do
9      if F = ∅ then L ← U; break            # 穷尽，U = OPT
10     L_F ← MIN-LB(F)
11     L ← max(L, L_F)
12     if L ≥ U then L ← U; break             # 最优性证书
13     if t mod K = 0 then
14         v ← EXPAND-FRONTIER(root)          # 强制探索，保证完备性
15     else
16         v ← SELECT-UCT(root)
17     if v = NONE then L ← U; break          # 根已关闭/无可行前沿
18     if TERMINAL(v) then
19         C ← Cmax(v)
20     else
21         C ← ROLLOUT(v)                     # 随机化 CP 优先表调度
22     if C < U then
23         U ← C
24         best ← (U, schedule-of(C))
25     BACKUP(v, C)
26     UPDATE-FRONTIER(v)
27 end for
28 return best, L, U, gap = (U - L) / max(1, L)
```

说明：

- 第 9 行 `F = ∅` 与第 12 行 `L ≥ U` 是两种不同的证书：前者是穷尽证书，后者是双侧界相遇证书。
- 第 13–16 行：正常用 UCT；每 `K` 轮强制从「有未尝试动作的最浅 open 节点」扩展一次，防止 UCT 长期忽略某个分支。`K = ∞` 时退化为纯 UCT（预算模式）；有限 `K` 用于认证模式。
- `SCHEDULE-OF(C)` 在 rollout 时记录完整 `(s, μ)`；实现上只需保存最优 rollout 的决策序列。

### 6.2 选择与扩展

```text
函数 SELECT-UCT(root)
────────────────────────────────────────────
1  stack ← [root]
2  while stack ≠ ∅ do
3      v ← top(stack)
4      if CLOSED(v) then pop(stack); continue
5      if v has untried actions then
6          a ← ARGMIN_{a ∈ untried(v), LB(child(a)) < U} PRIOR(a)
7          if no such a then
8              CLOSE(v); pop(stack); continue      # 回溯，不终止全局搜索
9          return EXPAND(v, a)
10     open_children ← { c ∈ children(v) : not CLOSED(c) }
11     if open_children = ∅ then
12         CLOSE(v); pop(stack); continue
13     push(stack, ARGMIN_{c ∈ open_children} UCT-SCORE(c, v))
14 end while
15 return NONE                       # 只有根也被关闭时才走到这里
```

`UCT-SCORE` 采用「代价最小化」版本：

```text
UCT-SCORE(c, v) = meanC(c) - c_p · sqrt( 2 · ln N(v) / N(c) )
```

其中：

- `meanC(c)` 是经过 `c` 的 rollout makespan 均值（越小越好）；
- `N(·)` 是访问次数；
- `c_p > 0` 是探索常数，默认 `c_p = 1/√2` 或 `1.0`；
- `N(c) = 0` 时优先级设为 `+∞`，但实际由第 3 行的未尝试动作优先处理。

`PRIOR(a)` 用字典序（越小越优先）：

```text
PRIOR(i, k) = ( LB(T(σ, (i, k))),  -q_i,  t,  -p_i )
```

即：优先选择子状态下界小、tail 大、开始早、处理时间长的动作。它只是未访问动作的排序，不影响正确性。

### 6.3 Rollout

```text
函数 ROLLOUT(v)
────────────────────────────────────────────
输入：状态 σ_v
1  σ ← σ_v
2  while Ready(σ) ≠ ∅ do
3      if Bernoulli(ε) then
4          i ← uniform(Ready(σ))
5      else
6          i ← argmax_{j ∈ Ready(σ)} (q_j, p_j)
7      k ← argmin_l A_l                   # 可行解优先，不刻意空闲
8      t ← max(A_k, max_{j∈pred(i)} c_j)
9      调度 i 于机器 k、开始时间 t
10     更新 σ
11 end while
12 return Cmax(σ) 及调度
```

`ε` 默认 0.1–0.2。纯 CP 优先（`ε = 0`）稳定但多样性不足；纯随机（`ε = 1`）多样性足但质量差。混合策略在原型中表现更稳。

可选增强（下一轮）：用 incumbent 调度的 ready 顺序做偏置，即「incumbent-biased rollout」。v0.1 不使用，以保持每次 rollout 独立、易分析。

### 6.4 关闭、剪枝与前沿维护

```text
函数 CLOSE(v)
────────────────────────────────────────────
1  标记 v 为 closed（pruned 或 exhausted）
2  从 F 中删除 v
3  若 parent(v) 的所有孩子都已关闭且无未尝试且 LB<U 的动作
4      then CLOSE(parent(v))            # 递归向上
```

```text
函数 UPDATE-FRONTIER(v)
────────────────────────────────────────────
1  若 v 是 open 且有未尝试且 LB(child)<U 的动作：把 v 加入 F
2  若 v 已关闭，或已无这样的未尝试动作：把 v 从 F 中删除
3  清理 F 中已关闭或 LB ≥ U 的节点
4  重建/惰性修正最小堆
```

实现细节：

- `EXPAND(v, a)` 创建子节点，计算 `LB(child)`；若 `LB(child) ≥ U`，直接标记 pruned，不放入 open 集合。
- `U` 下降后不立即全树扫描；所有选择/扩展路径都会重新检查 `LB ≥ U`，属于惰性剪枝。由于 `U` 单调不增，一旦某节点因 `LB ≥ U` 被剪，永远安全。
- 若一个节点的所有动作都因 `LB ≥ U` 被过滤，标记 exhausted；它不再贡献更优解。

### 6.5 输出

- **认证模式**：若因 `L ≥ U` 或 `F = ∅` 停止，输出 `U`，并声明 `U = OPT`。
- **预算模式**：若因 `t = B` 停止，输出 incumbent 调度、区间 `[L, U]` 与相对间隙 `(U - L) / max(1, L)`；不声明最优。
- 无论哪种模式，`U` 都是可行调度，`L` 都是合法下界。

## 7. 正确性论证

### 引理 1（下界可采纳）

已证于 5.1：任意从 `σ` 出发的完整调度满足 `Cmax ≥ LB(σ)`。

### 引理 2（前沿下界）

已证于 5.3：`L_F ≤ OPT`，因此 `L = max(L_0, L_F) ≤ OPT`。

### 引理 3（剪枝安全）

若在某个时刻 `LB(σ_v) ≥ U`，则 `v` 的任意完整扩展的 makespan 都 `≥ U`，不可能严格改进当前 incumbent。由于 `U` 只减不增，之后也不可能改进。因此把 `v` 标记为 pruned 不会删除任何严格优于最终 incumbent 的解。

### 引理 4（incumbent 可行）

初始 `U_0` 来自 CP 表调度，是可行调度；每次 `U` 更新都来自一个完整 rollout 或 terminal 节点，也是可行调度。因此始终 `U ≥ OPT`。

### 定理 1（任意时刻区间）

在算法运行的任意时刻，

```text
L ≤ OPT ≤ U
```

其中 `L` 是当前维护的全局下界（`L_0` 与历史 `L_F` 的最大值），`U` 是当前 incumbent。  
证明：引理 1、2 给出 `L ≤ OPT`；引理 4 给出 `OPT ≤ U`。

### 定理 2（双侧证书）

若算法因 `L ≥ U` 停止，则 `U = OPT`。  
证明：由定理 1，`L ≤ OPT ≤ U`；又 `L ≥ U`，故三者相等。

### 定理 3（穷尽证书）

若算法因 `F = ∅` 停止，则 `U = OPT`。  
证明：假设 `OPT < U`。由命题 1，存在一条根到叶的动作序列，其叶子 makespan ≤ `OPT < U`。沿这条路径，每个前缀状态 `σ` 都满足 `LB(σ) ≤ OPT < U`（引理 1），因此不会被剪枝；每个动作也不会被 `LB(child) ≥ U` 过滤。于是这条路径不会被完全关闭，`F` 不可能为空，矛盾。故 `OPT = U`。

### 定理 4（认证模式的有限完备性）

在认证模式下（`K` 有限，强制前沿扩展），若预算趋于无穷，算法最终停止并返回 `OPT`。  
证明草图：搜索树有限（每个任务至多调度一次，动作数有限）。`U` 是整数且单调下降，最多下降有限次。每次 `U` 下降只会让更多节点被剪，不会让已关闭节点重新打开。强制探索每 `K` 轮扩展一个「有未尝试动作的最浅 open 节点」，因此任何 `LB < U` 的未尝试动作最终都会被扩展；被 `LB ≥ U` 过滤的动作不可能包含更优解。于是要么某个时刻 `L ≥ U`，要么所有路径关闭、`F = ∅`；两种情形都由定理 2/3 给出 `U = OPT`。

### 推论 1（Graham 保证）

初始 incumbent 满足

```text
U_0 ≤ (2 - 1/m) · OPT
```

而算法只会改进 incumbent，所以最终 `U ≤ U_0`。

### 推论 2（误差界）

预算模式返回的相对间隙

```text
g = (U - L) / max(1, L)
```

满足 `OPT ∈ [L, U]`，因此相对误差至多 `g`。

## 8. 复杂度分析

记：

- `B`：迭代预算；
- `N`：物化节点数，`N ≤ B + 1`；
- `d ≤ n`：搜索深度；
- `b = |Ready(σ)| · m`：单节点动作数上界。

### 8.1 单次操作

- **预处理**：拓扑排序 + head/tail，`O(n + m)`。
- **`LB(σ)`**：`es_i` 的 DAG 动态规划 `O(n + |E|)`；注水下界二分 `O(m log(max A + W))`；合计 `O(n + |E| + m log(max A + W))`。
- **动作生成**：枚举 `b` 个动作，每个转移 `O(m + indeg(i))`，若逐个计算子状态下界则 `O(b · (n + |E|))`；去重哈希 `O(b)`；排序 `O(b log b)`。
- **Rollout**：朴素实现每步扫描 ready 与前驱，`O(n(n + |E|))`；用邻接表和最小堆可降到约 `O((n + |E|) log m)`。
- **Backprop**：沿路径 `O(d)`。
- **前沿堆更新**：`O(log N)` 每条位置。

### 8.2 每轮与总计

每轮最坏：

```text
O( d + b·(n + |E|) + n·(n + |E|) + log N )
```

总计：

```text
O( B · [ b·(n + |E|) + n·(n + |E|) ] )
```

空间：

```text
O( N · (n + m) + B )        （每个节点保存状态副本）
```

若使用哈希共享/置换表，可降低常数，但最坏仍是指数级。

### 8.3 最坏情况

`P | prec | Cmax` 是 NP-hard；认证模式可能遍历指数多个节点。DUB-MCTS 不改变最坏情况复杂度，它改变的是：

- 预算受限时的解质量；
- 能否给出 `[L, U]` 误差界；
- 能否在 `L = U` 或前沿穷尽时提前证明最优。

因此复杂度结论应表述为「每轮多项式，认证总时间最坏指数；这是 NP-hard 问题的预期行为」。

## 9. 实验设计与初步结果

### 9.1 原型实现

- 纯 Python，无外部依赖；
- 实现 5.1 的 `LB`、5.2 的 CP 初始上界、第 6 节的 UCT 主循环与随机化 CP rollout；
- 动作空间为 `(ready task, machine)`，允许主动空闲；
- 原型尚未实现 5.3 的前沿下界（只报根下界 `L_0`），因此下表的下界是偏保守的；
- 随机种子固定，所有实例可复现。

### 9.2 精确对照

**小规模随机 DAG**：`n ∈ {5,6,7,8}`，`m = 2`，边概率 0.3，工时 1–10；每个规模 5 个实例，共 20 个。精确解由「同一动作空间上的穷尽 DFS + 下界剪枝」给出。

| 规模 | CP 非最优实例 | DUB-MCTS 达到最优 |
|---|---:|---:|
| n=5 | 2/5 | 5/5 |
| n=6 | 2/5 | 5/5 |
| n=7 | 4/5 | 5/5 |
| n=8 | 2/5 | 5/5 |
| 合计 | 10/20 | 20/20 |

**独立任务、m=2**：`n ∈ {24,30,40}`，工时 1–100，共 18 个实例；用子集和 DP 精确求 partition 最优。

| 规模 | CP 非最优实例 | DUB-MCTS 达到最优 |
|---|---:|---:|
| n=24 | 5/6 | 6/6 |
| n=30 | 2/6 | 6/6 |
| n=40 | 3/6 | 6/6 |
| 合计 | 10/18 | 18/18 |

这两组结果主要验证**正确性**：动作空间确实覆盖最优，`LB` 没有错误剪枝，rollout 产生的上界可行。它们不证明 MCTS 的搜索效率。

### 9.3 较大实例与随机重启对照

`n ∈ {20,25,30,35}`，`m ∈ {3,4,5}`，随机 DAG，工时 1–30，每组 10 个实例，预算 300 次 rollout。比较：

- `CP`：初始 CP 表调度；
- `DUB`：DUB-MCTS（静态根下界版本）；
- `RAND`：同预算独立随机重启（不做树搜索）；
- 间隙以根下界 `L_0` 为分母，`gap = (mean C - L_0) / L_0`。

| 配置 (n,m,edge p) | mean L0 | mean CP | mean DUB | mean RAND | CP gap | DUB gap | DUB 严格优于 RAND |
|---|---:|---:|---:|---:|---:|---:|---:|
| 20,3,0.10 | 100.7 | 108.5 | 101.5 | 101.7 | 7.7% | 0.8% | 2/10 |
| 25,4,0.15 | 122.7 | 130.7 | 124.6 | 124.7 | 6.5% | 1.5% | 1/10 |
| 30,4,0.10 | 129.6 | 150.1 | 135.9 | 136.7 | 15.8% | 4.9% | 4/10 |
| 35,5,0.08 | 117.5 | 133.6 | 122.6 | 123.4 | 13.7% | 4.3% | 5/10 |
| 30,4,0.30 | 191.6 | 192.8 | 191.9 | 191.7 | 0.6% | 0.2% | 0/10（均值略逊于 RAND） |

**诚实解读**：

1. DUB 相对 CP 的改进是稳定的，尤其在 CP 间隙大的配置上。
2. DUB 相对同预算随机重启只有微弱、不稳定的优势；最后一组甚至均值略差。这说明 **UCT 在确定性调度上的统计引导尚未被证明有效**，当前收益有一部分来自「更多样的 rollout」而非树结构。
3. 这些实例规模小、分布随机，不能外推到强竞争/强依赖的工业实例。
4. 前沿下界 `L_F` 尚未进入原型；它是下一轮最优先的验证项。

### 9.4 下一轮实验清单

- **下界消融**：`LB_CP`、`LB_W`、`L_F` 分别去掉，测证书时间与剪枝率。
- **动作空间消融**：仅「最早机器」vs 显式 `(任务, 机器)`；验证主动空闲的必要性与代价。
- **rollout 消融**：`ε ∈ {0, 0.1, 0.3, 1.0}`；CP 优先 vs incumbent-biased。
- **搜索策略**：UCT vs 纯随机重启 vs best-first vs UCT+前沿强制扩展。
- **难例**：无依赖 partition（m=2/3）、fork-join、单长链 + 多短任务、PSPLIB 风格资源竞争。
- **规模**：`n = 20, 50, 100`，`m = 2, 4, 8`；每组 ≥ 30 个种子，报告均值、95% CI、证书率。
- **精确对照**：`n ≤ 12` 用 B&B/CP-SAT；`m=2` 用子集和 DP；其余报告 `[L,U]`。
- **指标**：相对精确解的 gap、相对下界的 gap、达到证书的迭代数/时间、anytime 曲线、峰值内存。
- **统计**：固定随机种子；对 MCTS 与随机重启做配对检验，避免只报均值。

## 10. 已知风险

1. **下界不够紧（首要风险）**：`LB_CP` 忽略机器争用，`LB_W` 忽略优先约束；在强依赖或强竞争实例上，两者可能都远离 `OPT`，导致既不能早停也不能有效剪枝。缓解：energetic reasoning、edge-finding、时间窗传播、预抢占松弛、拉格朗日松弛。
2. **UCT 在确定性优化中的有效性存疑**：rollout 均值是有偏的策略价值估计，不是状态最优值；原型中相对随机重启的优势很弱。缓解：best-first/UCT 混合、rollout 策略蒸馏、RAVE、逐步加宽、用下界做先验。
3. **动作空间爆炸**：显式 `(任务, 机器)` 加主动空闲使分支因子达到 `m·|Ready|`；虽然覆盖最优，但大量动作是支配或对称的。缓解：机器对称去重、状态支配、置换表、只对关键任务保留空闲选项。
4. **前沿下界的实现复杂度**：`L_F` 需要维护切口、惰性删除和单调化；若实现错误，可能把「未探索动作」误判为已关闭，导致错误的证书。缓解：把前沿维护做成独立模块，用随机小实例与穷尽搜索对拍；任何证书都必须能回溯出一条完整的关闭证明。
5. **状态复制与内存**：每个节点保存 `A`、`c` 与路径，`n` 大时内存增长快。缓解：持久化数组、哈希共享、只保存边界完成时间、限制树宽。
6. **模型假设**：整数工时、确定性、无机器释放时间、无批处理/准备时间。随机工时需要 chance node，剪枝从「逐样本」变成「期望/分位数」，当前的可采纳性证明不直接适用。
7. **零工时与连续时间**：`p_i = 0` 会破坏「前驱严格早于后继」的排序论证；连续时间下 `LB ≥ U` 的严格剪枝需要 epsilon 处理。
8. **预算模式没有最优性保证**：只返回 `[L,U]`；若 `L` 很松，间隙可能很大。文档和接口必须明确区分「认证」与「预算」两种模式，避免误用。

---

## 11. 一句话最大风险

**当前方案最大的风险是：依赖下界在强依赖/强竞争实例上可能长期远离最优，使 MCTS 既剪不掉分支也给不出最优性证书，最终退化为昂贵的随机重启。**
