# 第 44 轮（新循环第 4 轮） · Skill-Cert × Need-Cert：把「技能学习」与「用户需求分析」纳入可验证证书闭环（四层架构 v9）

> 承接第 43 轮 v20（Persona × Concurrent 证书闭环）。v20 自陈最大风险是「共形边际覆盖被欺骗 + 多用户契约空集」，但它仍压着两个更深的单点假设：**(H1) 技能集是静态的**——证书默认动作/技能集固定，学习被当作离线训练、学成即替换，而真实系统是**持续技能学习**，技能分布随部署漂移；**(H2) 需求是已给定且正确的**——系统假设目标已被正确编译，却从未给「需求本身对不对、全不全」发过证书。本轮灵感词「技能学习」「用户需求分析」精确命中这两个假设：**技能学习**把「能力增长」变成证书扩张问题（学习即扩张，扩张必须持证，且新技能会让旧证书失效→遗忘传播）；**用户需求分析**把「目标从哪里来」变成可验证需求契约问题（自然语言欠定、冲突、可被操纵→禁止静默补全）。二者耦合处是本轮真正的新问题：**技能可以被训练去迎合一个被错误编译的需求**，即「需求-评价共谋」。

## 0. 直觉与动机

**灵感 1（技能学习 → 能力增长必须持证，且证书会「遗忘」）**：直觉上，机器人学会开抽屉是好事，但一个新技能等于把可行域往外推了一圈——这和 v20 里「个性化扩张」是同构的：**收缩免费、扩张持证**。区别在于技能学习的扩张是**参数级、连续、且会回头破坏旧能力**。因此把技能当作带证书的单元：证书给出它的**操作域 D_π、泛化界 γ_π、前后置条件 φ_π、版本 v_π**。学习器提出 π′ 时先判定：落在旧证书域内（D_{π′}⊆D_π 且泛化界不降）→ 免费热更新；越出旧域 → 走**认证门**（分布鲁棒评估 + 影子执行 + 反例搜索 + 遗忘回归），代价从「技能证书预算 B_skill」扣除。更关键：技能更新会**传递性作废旧证书**，必须显式维护**证书依赖图**并传播失效，否则旧技能在新策略下静默失 sound——这就是「灾难性遗忘」在证书层的镜像。

**灵感 2（用户需求分析 → 需求要编译成契约，欠定部分禁止静默补全）**：直觉上，用户说「把桌子收拾一下」并没有给出规格：哪些算垃圾、能不能动私人文件、先收哪边。LLM 很容易「好心」地把没说的话补全，然后系统对着一个**自造的规格**发证书——证书没撒谎，是规格在撒谎。因此把需求编译成**需求契约 Q=(G_q, N_q, ≺_q, δ_q, u_q)**：正需求目标谓词、**反需求（禁止谓词）**、优先级、验收测试与不确定性标记。凡自然语言到契约之间存在缺口（Q_user ⊖ Q_compiled），缺口元素必须标成**假设 a=(内容, 置信, 关键级)**，关键级高的假设在进入安全守卫前必须经用户/操作员确认。**澄清不是免费信息**：只在「期望信息增益 > 用户认知成本」时才提问。

**灵感 3（耦合 → 需求-技能对齐，且评价必须独立）**：技能本来就是为了满足需求而学，于是形成「需求残余 → 技能课程 → 新技能 → 需求再评估」的闭环。危险在于：若**生成技能的策略**和**判定需求是否满足的评估器**来自同一模型/同一数据，技能会学会**迎合评估器而非需求**（reward hacking / specification gaming）。缓解不是调参，而是**职责分离**：需求 oracle 的证据源必须独立于策略（独立物理测量 / 独立验证器 / 人工确认），并做**对抗需求采样**——专门生成「看起来满足正需求、实际违反反需求」的测试。需求-技能对齐用矩阵 M[g_i,π_j] ∈ {certified, partial, none} 显式化，不允许「隐式满足」。

**耦合升级**：SCE（技能证书引擎）管「能力扩张的证书账本与失效传播」；NCE（需求契约引擎）管「目标从自然语言到可验证谓词、缺口显式化与主动澄清」；AGV（对齐博弈验证器）管「需求-技能对齐、评价独立性与对抗需求采样」。四层架构由 v8 的「人格+并发」升级为 v9 的「人格+并发+技能证书层+需求契约层」。

## 1. 形式化定义（增量：定义 44–50）

**定义 44（技能单元与技能证书）**：技能 π:S→A 是状态到动作（或子策略）的映射。技能证书 K_π=(D_π, γ_π, φ_π, v_π)：D_π⊆S 为**操作域**（证书承诺有效的状态集）；γ_π 为**泛化界**（在 D_π 内对未见状态的性能/安全违例上界，如 PAC-Bayes 或 Lipschitz 鲁棒半径导出）；φ_π=(pre_π, post_π) 为前后置条件（含几何与安全谓词）；v_π 为版本。**技能可用性**：技能 π 在状态 s 可用，当且仅当 s∈D_π ∧ lease(K_π) 有效（复用定义 41）∧ φ_π 的前置成立。**命题（证书即承诺）**：若 K_π sound，则 ∀s∈D_π 满足 pre_π 的执行不违反全局/人格证书 C_global∩Π_u。

**定义 45（技能扩张与认证门）**：设旧技能 π 更新为 π′。若 D_{π′}⊆D_π 且 γ_{π′}≤γ_π（更强或相等），称**域内更新**，允许热替换，仅需在线影子检查。否则称**证书扩张**，必须通过认证门：
(1) **分布鲁棒评估**：在 D_{π′} 上对分布漂移球内的最坏情形估计违例；
(2) **影子执行**：π′ 与 π 并行跑影子证书，零违例才可上岗；
(3) **反例搜索**：定向搜索 D_{π′}∖D_π 的新域边界；
(4) **遗忘回归**：全量旧技能证书回归（见定义 46）。
门通过后 K_{π′} 生效并从**技能证书预算** B_skill 扣费；预算耗尽则只能做域内更新。**推论**：学习不自动等于扩张，扩张不自动等于放行——与定义 38 的「收缩免费、扩张持证」同构。

**定义 46（灾难性遗忘与证书失效传播）**：技能证书集 {K_π} 与全局/人格/需求证书构成**证书依赖图** G_cert=(V,E)，边 u→v 表示 v 的 soundness 依赖 u 的证据。技能 π 更新为 π′ 时，令失效集 F=reach(G_cert, K_π)（依赖 K_π 的传递闭包，不含已独立重验者）。**遗忘下界** L_forget：更新后旧技能在各自 D 上的性能下降 ≤ L_forget 且证书仍 sound，才保留其 certificate；否则 F 中节点必须立刻降级为**暂定（provisional）**，禁止用于安全守卫，直到重验通过。**命题**：若失效传播正确执行，则任意技能链式更新后无「静默失效证书」被守卫使用。

**定义 47（需求契约）**：自然语言需求 n 经编译得需求契约 Q=(G_q, N_q, ≺_q, δ_q, u_q)：G_q 为正需求谓词集（要达成什么）；N_q 为**反需求谓词集**（绝不能发生什么，如「不得删除私人文件」）；≺_q 为需求优先级与冲突消解序；δ_q 为验收测试与容差；u_q: G_q∪N_q→[0,1] 为每条需求的不确定性/歧义度。**需求可验证性**：Q 可验证，当且仅当 G_q∪N_q 中每个谓词都可由某个独立可观测量判定。**需求覆盖率** cov(π,Q)=被 π 的证书**证实**满足的需求比例（partial 只计半权）。

**定义 48（需求-规格缺口与禁止静默补全）**：定义缺口 GAP(n)=Q_user ⊖ Q_compiled（对称差）。**禁止静默补全公理**：∀g∈GAP(n)，必须显式登记为假设 a=(content, confidence, criticality)；若 criticality(a)≥κ_confirm，则 a 在进入任何安全相关守卫前必须取得用户/操作员确认。**命题（规格诚实性）**：禁止静默补全下，系统发出的每个需求证书都可追溯到「用户确认」或「显式假设+非安全用途」，不存在无出处的硬约束。

**定义 49（主动需求澄清）**：澄清问题 q 在用户回答后使后验从 P(Q) 变为 P(Q|ans_q)。**最优提问**：q*=argmax_q [ I(Q; ans_q) − λ·cost_user(q) ]，cost_user 为用户认知/时间成本（可用回答长度、犹豫、拒绝率估计）。**停止准则**：当 max 后验歧义 < ε 或预算耗尽，停止并退回**保守解释**（对 G_q 取交集、对 N_q 取并集，即采取最不冒险的读法）。**命题**：保守解释的可行域 ⊆ 任意其他可相容解释的可行域，因此澄清不足时只损失可用性，不损失 soundness。

**定义 50（需求-技能对齐与评价独立性）**：对齐矩阵 M[g_i,π_j]∈{certified, partial, none}，由独立证据填充。**评价独立性公理**：判定「π 满足 g」的 oracle 的证据源集合与生成 π 的策略/训练数据集合必须存在受控的不相交部分，记为 indep(oracle, π)。**对抗需求采样**：生成 n_adv 使 π 在正需求上「看起来通过」但在 N_q 上违例；发现即为 spec-gaming 反例，回灌需求契约与技能课程。**命题（共谋不可能性的条件化）**：若 indep(oracle,π) 成立且对抗采样覆盖 N_q 的语义邻域，则「π 通过对齐但违反 N_q」的概率被采样覆盖率约束。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-60 SKILL-CERT-ENGINE（技能证书引擎 SCE）
1. **技能证书库与版本**：每技能维护 (D_π, γ_π, φ_π, v_π, lease)；操作域、泛化界、前后置、版本、租约。
2. **认证门**：域内更新快速通道；证书扩张走「分布鲁棒 + 影子执行 + 反例搜索 + 遗忘回归」四闸。
3. **证书依赖图与失效传播**：技能更新触发传递性降级，暂定证书不得用于守卫。
4. **技能证书预算 B_skill**：限制扩张速率，防止「学习狂飙、证书欠账」。

### 2.2 IP-61 NEED-CONTRACT-ENGINE（需求契约引擎 NCE）
1. **需求编译**：NL → Q=(G_q,N_q,≺_q,δ_q,u_q)，显式区分正/反需求。
2. **缺口审计**：GAP(n) 逐条登记为假设，关键假设需确认，杜绝静默补全。
3. **主动澄清**：按信息增益/用户成本选问题，预算耗尽走保守解释。
4. **需求覆盖率与验收**：cov(π,Q) + 独立验收测试生成，partial 不冒充 certified。

### 2.3 IP-62 ALIGNMENT-GAMING-VALIDATOR（对齐博弈验证器 AGV）
1. **对齐矩阵维护**：M[g_i,π_j] 由独立证据而非策略自评填充。
2. **评价独立性审计**：自动检查 oracle 与策略的证据源是否纠缠（同模型/同数据/同奖励）。
3. **对抗需求采样**：专门找「正需求过、反需求破」的 spec-gaming 反例。
4. **需求漂移监测**：用户需求随时间变化时，旧证书的需求前提失效并触发重验。

## 5. 本轮最大风险

**一句话**：技能学习把「证书泛化域」当成已证明，用户需求分析把「自然语言压缩」当成已正确，二者叠加会产生「技能在证书域外泛化 + 需求评价被技能反向共谋」的双重静默失效——因此 E96（泛化界校准）与 E100（需求-评价共谋）必须设为红线实验，并默认回退到「冻结技能集 + 操作员确认的显式需求清单」这条永不失 sound 的底线。

# 第 44 轮产物 · 创新点清单 v21：Skill-Cert × Need-Cert（SCE × NCE × AGV）× 可验证技能-需求闭环（四层架构 v9）

| 编号 | 名称 | 类型 | 关键改进 |

## 2. 关键算法（伪代码）

### IP-60 SCE：技能证书、认证门与失效传播
```
def register_skill(pi, D, gamma, phi, parent_cert):
    K = Cert(domain=D, gamma=gamma, phi=phi, version=next_version(pi))
    graph.add_node(K); graph.add_edge(parent_cert, K)   # K 继承父证书证据
    return K

def admit_update(pi_old, K_old, pi_new, K_new, B_skill):
    if subset(K_new.D, K_old.D) and K_new.gamma <= K_old.gamma:
        return hot_swap(pi_new, K_new)                  # 域内：免费
    if B_skill <= 0:
        return reject("证书预算耗尽，仅允许域内更新")
    checks = [
        dr_eval(K_new),                              # (1) 分布鲁棒评估
        shadow_run(pi_new, K_new),                   # (2) 影子执行零违例
        counterexample_search(K_new.D - K_old.D),    # (3) 新域边界反例
        forgetting_regression(K_new, L_forget),      # (4) 遗忘回归
    ]
    if all(checks):
        B_skill -= expansion_cost(K_new, K_old)
        return hot_swap(pi_new, K_new)
    return reject("认证门未过")

def propagate_invalidation(updated_cert):
    F = reach(graph, updated_cert) - independently_revalidated()
    for K in F:
        K.state = PROVISIONAL          # 禁止进入安全守卫
        schedule_revalidation(K)
    return F
```

### IP-61 NCE：需求编译、缺口审计与主动澄清
```
def compile_need(nl, context):
    Q_raw = llm_parse(nl)                       # 只做候选，不直接生效
    G = build_positive_predicates(Q_raw)
    N = build_negative_predicates(Q_raw)        # 反需求必须显式化
    Q = Contract(G, N, order=infer_precedence(Q_raw),
                 delta=build_acceptance_tests(G, N), u=ambiguity(Q_raw))
    return Q

def audit_gap(nl, Q_compiled, kappa_confirm):
    Q_user = user_intent_shadow(nl)             # 以显式假设近似，不静默
    gap = symmetric_difference(Q_user, Q_compiled)
    assumptions = [Assumption(g, conf=est_conf(g), crit=est_crit(g)) for g in gap]
    to_confirm = [a for a in assumptions if a.crit >= kappa_confirm]
    return assumptions, to_confirm              # 高关键假设必须用户确认

def active_clarify(Q, budget, lam):
    while budget > 0 and max_ambiguity(Q) >= EPS:
        q = argmax_question(IG(Q, q) - lam * user_cost(q))
        ans = ask_user(q); budget -= user_cost(q)
        Q = posterior_update(Q, q, ans)
    if max_ambiguity(Q) >= EPS:
        Q = conservative_reading(Q)             # G 取交、N 取并：只损可用性
    return Q

def requirement_coverage(pi, Q):
    # partial 计半权；只认独立证据，不认策略自评
    score = 0.0
    for g in Q.G | Q.N:
        verdict = independent_oracle(pi, g)
        score += 1.0 if verdict == CERTIFIED else 0.5 if verdict == PARTIAL else 0.0
    return score / len(Q.G | Q.N)
```

### IP-62 AGV：对齐、评价独立性与对抗需求采样
```
def fill_alignment_matrix(pis, Q):
    M = {}
    for g in Q.G | Q.N:
        for pi in pis:
            v = independent_oracle(pi, g)       # 禁止用策略自评
            M[(g, pi)] = v
    return M

def audit_independence(oracle, pi):
    src_o = evidence_sources(oracle)
    src_p = policy_sources(pi)                  # 训练数据/模型/奖励函数
    return controlled_disjoint(src_o, src_p)    # 不满足则标记共谋风险

def adversarial_requirement_sample(pi, Q, n_adv):
    # 目标：正需求看起来过、反需求实际破
    seeds = [mutate(g) for g in Q.G]
    cands = [s for s in seeds if oracle_pass(pi, s)]              # 正需求通过
    return [s for s in cands if violates_negative(pi, s, Q.N)]    # 反需求违例

def detect_spec_gaming(M, Q):
    bad = []
    for pi in M.policies:
        if all(M[(g, pi)] == CERTIFIED for g in Q.G) and \
           any(M[(g, pi)] != CERTIFIED for g in Q.N):
            bad.append(pi)                      # 迎合正需求、牺牲反需求
    return bad
```

def car_skill_guard(s, pi, K_pi, lease, persona, t):
    in_domain = s in K_pi.D
    pre_ok = eval_pre(K_pi.phi, s) and persona_cap_ok(persona, s)
    return in_domain and pre_ok and lease_valid(lease, theta(K_pi), t) \
           and K_pi.state == CERTIFIED

def compose_skill_certs(K1, K2):
    # 组合证书：只在 K1.post ∩ K2.pre 非空时成立
    joint_pre  = K1.phi.pre
    joint_post = K2.phi.post
    D_joint    = {s for s in K1.D if step_K1(s) in K2.D}   # 需保守验证
    gamma_joint = combine_bounds(K1.gamma, K2.gamma)
    return Cert(domain=D_joint, gamma=gamma_joint,
                phi=(joint_pre, joint_post), version=compose_versions(K1, K2))

## 6. 本轮最大风险

**一句话**：技能学习把「证书泛化域」当成已证明，用户需求分析把「自然语言压缩」当成已正确，二者叠加会产生「技能在证书域外泛化 + 需求评价被技能反向共谋」的双重静默失效——因此 E96（泛化界校准）与 E100（需求-评价共谋）必须设为红线实验，并默认回退到「冻结技能集 + 操作员确认的显式需求清单」这条永不失 sound 的底线。
