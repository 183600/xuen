### 新一轮第 1 轮灵感驱动研究记录（承接 v29 → v30）

**灵感词**：关节空间控制、用户需求分析

**直觉与动机**：

先给直觉。v29 的十二证体系已经把「价值对齐」推进到了动作层，但整条证书链仍悬在**任务空间**与**学习模型**上：一个任务空间上完美、价值上全绿的计划，落到真实双足上仍可能因为膝/踝力矩饱和、关节限位、自碰撞或奇异位形而不可执行；而「用户到底要什么」也被压缩成了一个标量价值 `V_ψ`。两个灵感词恰好戳中这两个断层：

- **关节空间控制**提醒我们：安全与常识最终要在执行器与关节约束上兑现，「任务空间可容许」不等于「关节空间可实现」；
- **用户需求分析**提醒我们：价值模型是对偏好的统计拟合，而需求是有身份、有优先级、会冲突、会变更的规范性陈述，二者不能互相替代。

于是本轮提出一条「需求—关节」双层证书链：把用户需求显式建模、可追踪地编译为关节空间约束，再用关节空间可实现性证书为任务空间计划兜底。

1. **关节空间可实现性（JRC）**：定义关节可容许集 `Q_adm(t)`（限位、速度、力矩/热降额、自碰撞、可操作度），以及任务轨迹到关节轨迹的「提升算子」`L`。JRC 不是新的优化器，而是对已有 KT-MPC 计划的**存在性检查 + 裕度量化**：`∃Q_{0:N}` 使 `FK(q_k)=x_k`、`Q_k∈Q_adm`、且离散速度一致。关键是给出从任务空间量（跟踪误差 `ε_x`、Jacobian 条件数 `κ_max`）到关节空间量（`|q̇|`、`|τ|`）的**可实现性传递引理**，使证书能廉价地由已有量推出，而不必每步解完整逆动力学。

2. **需求可追踪与覆盖（RTCA/RCC）**：把用户需求形式化为带优先级与验收判据的谓词集合 `R`，建立需求→证书的追踪矩阵 `M`，并区分三种状态：被某证书语义蕴含（covered）、不可编译的语义残差（residual）、与其他需求冲突（conflict）。RCC 要求高优先级需求覆盖率 = 1、语义残差质量 `m_sem ≤ m_sem_max`、冲突必须显式裁决。这样「需求分析」不是写文档，而是进入证书语义。

3. **需求编译器（JSRC）**：把「走路安静」「别伤膝盖」「保持平衡」这类人类语言需求编译为关节速度/加加速度、膝力矩/热约束、踝髋力矩裕度等关节空间约束；编译不了的需求必须留下残差标签，而不是悄悄丢弃。

**关键洞见**：v29 的风险是「学习组件共因失效」；v30 把防线往物理侧挪了一步——关节约束是硬的、可测量的。但代价是引入了一个新的、更上游的失效面：**需求到证书的语义翻译**。物理证书再硬，也只能证明「你执行了一个被错误规格化的任务」。

**形式化目标（增量）**：

1. 定义 `Q_adm(t)` 与提升算子 `L`，定义 JRC 与可实现性裕度 `ρ_J`；
2. 证明可实现性传递引理：任务空间误差/条件数 → 关节速度/力矩上界；
3. 定义需求模型 `R`、追踪矩阵 `M`、语义蕴含关系 `⊨`、语义残差质量 `m_sem`；
4. 定义 RCC 与冲突检测（LP/SMT），给出需求变更下的重认证规则；
5. 定义 v30 十四证执行集 `Exec_v30 ⊆ Exec_v29`，并给出实验设计验证 JRC 降低关节违规、RCC 降低需求漏检，同时量化「名义覆盖 vs 语义覆盖」的差距。

**本轮最大风险**：**需求-证书映射的语义空洞（requirement laundering）**——追踪矩阵可以用名义链接填满，JRC 只能证明关节可行、不能证明高层需求被满足；一旦 JSRC 把不可编译的需求静默丢进残差且 `m_sem` 被低估，RCC 会以高覆盖率放行一个「物理上安全、规格上错误」的系统，这比 v29 的共因失效更上游、也更难在运行时发现。

## 2. 关键算法骨架

### IP-473 Joint-Space Admissibility Model (JSAM)

```python
@dataclass
class JointSpaceAdmissibilityModel:
    """JSAM：把关节限位/速度/力矩/热/自碰撞/可操作度统一为归一化裕度"""
    q_min: np.ndarray; q_max: np.ndarray
    dq_max: np.ndarray; tau_rated: np.ndarray
    T_max: float; d_min: float = 0.02; sigma_min: float = 0.02
    thermal: 'ThermalModel'

    def tau_max(self, T_j: np.ndarray) -> np.ndarray:
        """热降额：结温超过拐点后线性下降，防止证书忽略执行器发热"""
        derate = np.clip((self.T_max - T_j) / self.T_max, 0.05, 1.0)
        return self.tau_rated * derate

    def margin(self, q, dq, tau, T_j) -> float:
        """返回最紧约束的归一化裕度；<0 即不可容许"""
        slacks = [
            self._range_slack(q, self.q_min, self.q_max),
            self._range_slack(dq, -self.dq_max, self.dq_max),
            self._range_slack(tau, -self.tau_max(T_j), self.tau_max(T_j)),
            (self.d_self(q) - self.d_min) / self.d_min,
            (self.sigma_min_j(J(q)) - self.sigma_min) / self.sigma_min,
        ]
        return float(np.min(slacks))
```

### IP-474 Task-to-Joint Realizability Certificate (TJRC)

```python
@dataclass
class TaskToJointRealizabilityCertificate:
    """TJRC：对既有任务轨迹做关节提升 + 存在性检查（不新增优化器）"""
    jsam: JointSpaceAdmissibilityModel
    ik: 'RedundancyResolvingIK'
    rho_min: float = 0.05
    eps_x: float = 0.01

    def lift(self, X, q_prev):
        """逐点冗余分解 IK + 离散速度一致性；返回 Q 或 None（局部极小/不可达）"""
        Q = []
        for x_k in X:
            q_k = self.ik.solve(x_k, warm_start=q_prev)
            if q_k is None:
                return None
            Q.append(q_k); q_prev = q_k
        return np.asarray(Q)

    def certify(self, X, T_j, dt):
        """存在性证书：sound 但不 complete（见引理 30）"""
        Q = self.lift(X, self.ik.q_ref)
        if Q is None:
            return False, None, -1.0
        rho = min(self.jsam.margin(Q[k], dq, tau, T_j)
                  for k, (dq, tau) in enumerate(self._fd_dynamics(Q, dt)))
        return rho >= self.rho_min, Q, rho

    def certify_fast(self, v_x, a_x, kappa_max) -> bool:
        """引理 29 快速路径：仅用任务空间量给出速度/力矩的充分界"""
        dq_ub = kappa_max * v_x
        tau_ub = (self.M_max * (a_x + self.Jdot_max * dq_ub)
                  + self.C_max * dq_ub ** 2 + self.G_max)
        return bool(dq_ub <= self.jsam.dq_max.min()
                    and tau_ub <= self.jsam.tau_rated.min())
```

### IP-475 Requirement Traceability & Coverage Auditor (RTCA)

```python
@dataclass
class RequirementTraceabilityAuditor:
    """RTCA：需求不是文档，而是带语义蕴含关系的可检验对象"""
    requirements: list          # [Requirement(id,type,phi,pi,accept)]
    trace: dict                 # M: req_id -> [cert_id]
    prover: 'ImplicationProver' # 检验 cert ⊨ req，必须给出证明项而非人工勾选
    w: dict                     # 需求权重
    m_sem_max: float = 0.10
    pi_0: int = 2               # 高优先级门槛

    def audit(self, active_certs) -> 'RCC':
        covered, residual = set(), set()
        for r in self.requirements:
            if any(self.prover.prove(c, r) for c in self.trace.get(r.id, [])
                   if c in active_certs):
                covered.add(r.id)
            else:
                residual.add(r.id)
        self.cov = self._weighted(covered) / self._total()
        self.m_sem = self._weighted(residual) / self._total()
        self.conflicts = self._detect_conflicts()      # LP/SMT
        high = {r.id for r in self.requirements if r.pi >= self.pi_0}
        rcc_ok = (high <= covered and self.m_sem <= self.m_sem_max
                  and not self.conflicts)
        return RCC(rcc_ok, self.cov, self.m_sem, self.conflicts, residual)

    def _detect_conflicts(self):
        """需求冲突：在 Q_adm 上 C(r_i)∩C(r_j)=∅；不可判定则升级人工"""
        return [(a.id, b.id) for a, b in itertools.combinations(
                    self.requirements, 2)
                if self.prover.unsat_on_admissible(a, b)]
```

### IP-476 Joint-Space Requirement Compiler (JSRC)

```python
class JointSpaceRequirementCompiler:
    """JSRC：需求模板 → 关节空间约束；不可编译项显式落 residual"""
    TEMPLATES = {
        'quiet_walk':   lambda p: [JerkLimit(p.jerk_max), VelLimit(p.v_max)],
        'protect_knee': lambda p: [TorqueLimit('knee', p.tau_cap),
                                   ThermalLimit('knee', p.T_cap)],
        'keep_balance': lambda p: [TorqueMargin('ankle', p.ankle_margin),
                                   TorqueMargin('hip', p.hip_margin)],
    }

    def compile(self, r):
        tpl = self.TEMPLATES.get(r.template)
        if tpl is None:
            return [], Residual(r.id, reason='no_template')   # 绝不静默丢弃
        constraints = tpl(r.params)
        if not self._joint_expressible(constraints):
            return [], Residual(r.id, reason='not_joint_expressible')
        return constraints, None
```

### IP-477 Requirement-Aware Joint MPC (RAJ-MPC)

```python
class RequirementAwareJointMPC:
    """RAJ-MPC：任务空间规划 → 关节提升/JRC → 失败则收紧重规划 → 教师兜底"""
    def solve(self, x0, req_constraints, T_j):
        for scale in (1.0, 0.7, 0.4):
            X = self.kempc.plan(x0, aggressiveness=scale)        # 任务空间
            ok, Q, rho = self.tjrc.certify(X, T_j, self.dt)      # 关节空间
            if ok and self._satisfies(Q, req_constraints):
                return Q, 'jrc_ok'
        return self.kempc.solve_teacher_action(x0), 'teacher_fallback'
```

### IP-478 Joint-Requirement Cert Gate (JR-CG)

```python
@dataclass
class JointRequirementCertGate:
    """JR-CG：v29 十二证 + JRC + RCC = 十四证；教师路径逐字节复用 v29"""
    vad_ktcg: 'ValueAlignedDistillationCertGate'
    tjrc: TaskToJointRealizabilityCertificate
    rtca: RequirementTraceabilityAuditor
    jsrc: JointSpaceRequirementCompiler

    def admits(self, robot_plan, sensor_data, plan_req_hash):
        # 0) RCC 在线只读 + 需求版本一致性（防漂移后使用过期矩阵）
        rcc = self.rtca.audit(active_certs=self._active())
        if plan_req_hash != self.rtca.mu_req or not rcc.ok:
            return self._teacher_path(robot_plan, sensor_data)

        # 1) v29 十二证原样复用（学生先行-证书裁决-教师兜底）
        ok29, u29, path = self.vad_ktcg.admits(robot_plan, sensor_data)
        if not ok29:
            return False, u29, path

        # 2) JRC：任务轨迹必须存在关节实现且裕度足够
        ok_j, Q, rho = self.tjrc.certify(robot_plan.X, sensor_data.T_j, self.dt)
        if not ok_j:
            return self._teacher_path(robot_plan, sensor_data)

        return True, u29, 'joint_certified'

    def _teacher_path(self, robot_plan, sensor_data):
        ok = self.vad_ktcg.admits(robot_plan, sensor_data)
        return ok, self.vad_ktcg.last_u_cmd, ('teacher' if ok else 'fallback')
```

**与 v29 的接口约定**：`VAD-KTCG.admits` 语义不变；新增只读属性 `robot_plan.X`（任务轨迹）、`sensor_data.T_j`（结温）、`plan_req_hash`。JSAM/TJRC/RTCA/JSRC 均为增量，不修改既有证书判据。

## 3. 复杂度分析（增量更新）

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 |
|---|---|---|---|
| JSAM 单点裕度 | O(n²)（Jacobian 奇异值） | O(n) | n=12，<0.02ms |
| TJRC 提升（逐点 IK） | O(N·iter·n³) | O(N·n) | N=20，iter≤20，~1-3ms |
| TJRC 快速路径（引理 29） | O(1) | O(1) | <0.01ms |
| RTCA 审计（离线/版本变更） | O(\|R\|·\|C\|·T_prove) | O(\|R\|·\|C\|) | 在线仅比对 `μ_req`，O(1) |
| 冲突检测（LP/SMT） | 最坏指数，实测 O(\|R\|²) | O(\|R\|²) | 离线，\|R\|~30 |
| JSRC 编译 | O(\|R\|) | O(\|R\|) | 离线 |
| RAJ-MPC 单步 | 期望 +1-3ms；最坏 3×KT-MPC | O(N·n) | 收紧重规划至多 3 次 |
| JR-CG 单步 | 期望 v29 + 2ms；最坏 = 教师 + TJRC | O(N·n) | 不劣化最坏语义 |

**实时性**：JRC 快速路径可把大多数正常步压到 <0.05ms；只有快速路径不可判定时才走逐点 IK。需求审计全部离线，在线仅做版本哈希比对。

## 4. 正确性论证（增量更新）

### 引理 29（任务空间→关节空间的传递界）

**陈述**：设 `ẋ=J(q)q̇` 且 `σ_min(J(q))≥σ_min>0`。若 `‖ẋ‖≤v_x`，则 `‖q̇‖≤v_x/σ_min`。进一步若 `‖ẍ‖≤a_x` 且 `‖J̇‖≤Jdot_max`，则
`‖τ‖ ≤ M_max·(a_x + Jdot_max·v_x/σ_min)/σ_min + C_max·(v_x/σ_min)² + G_max`。

**证明**：由 `q̇=J^+ẋ` 及 `‖J^+‖=1/σ_min` 得速度界。对加速度，`ẍ=Jq̈+J̇q̇` 给出 `‖q̈‖≤(‖ẍ‖+‖J̇‖‖q̇‖)/σ_min`。代入逆动力学 `τ=M(q)q̈+C(q,q̇)q̇+G(q)` 并用各项保守界即得。∎

**工程含义**：快速路径只需任务空间量即可给出关节速度/力矩的**充分**上界；但限位、自碰撞、可操作度无法由该界推出，必须走逐点 IK。因此快速路径只能「快速否决/放行速度力矩维」，不能替代完整 JRC。

### 引理 30（JRC 的可靠性 soundness，非完备性）

**陈述**：若 `TJRC.certify(X)=True`，则存在返回的 `Q` 满足 `FK(Q_k)=x_k`（误差 ≤ ε_x）、`Q_k∈Q_adm`、且离散速度一致；即 JRC 是可靠的。反之 `certify=False` 不蕴含不存在可行提升（可能落入冗余分解的局部极小）。

**证明**：可靠性由构造直接得到：每个 `q_k` 由 IK 返回并校验残差，`ρ_J≥ρ_min` 逐点检查全部约束。非完备性来自冗余分解 IK 的局部极小：存在另一组可行解而当前 warm-start 未找到，故为假阴性。∎

**工程含义**：JRC 宁可误拒不可误放（保守），但会把「可实现」误判为「不可实现」，造成教师兜底率上升——这是 R28 的来源。

### 引理 31（零残差下的需求覆盖可靠性）

**陈述**：设 `m_sem=0`、无未裁决冲突，且每个高优先级 `r_i` 都存在活跃证书 `c_j` 使 `c_j ⊨ r_i`（证明项通过机器检验）。则任何被 JR-CG 准入的执行都满足全部高优先级需求。若 `m_sem>0`，则只有被覆盖需求被保证，需求违规质量上界为 `ε_req ≤ m_sem`。

**证明**：`m_sem=0` 时高优先级需求全部落入 covered，`⊨` 的可靠性把证书成立传递为需求满足，执行被准入门约束在证书成立集内，故需求满足。`m_sem>0` 时违规只能来自 residual 集合，其权重质量恰为 `m_sem`，其余 covered 需求由 `⊨` 保证。∎

**注意**：`⊨` 的可靠性完全取决于证明项的真实性；若追踪矩阵用名义链接（人工勾选、字符串匹配）冒充 `⊨`，引理 31 的前提被绕过——这正是本轮最大风险的形式化入口。

### 引理 32（需求漂移的陈旧窗口界）

**陈述**：设需求以速率 `ΔR/Δt` 变化，RCC 每 `T_reaudit` 重算一次。则两次重认证之间新增的未覆盖需求质量 `≤ (ΔR/Δt)·T_reaudit`。若在线对每个计划校验 `plan_req_hash == μ_req`，则版本不一致的计划被直接送教师路径，陈旧窗口内的暴露为 0（代价是兜底率上升）。

**证明**：漂移质量按定义线性累积；哈希不一致即拒绝使用旧矩阵，故不产生未覆盖暴露。∎

### 定理（JR-CG 十四证准入门的执行集收缩）

**陈述**：`Exec_v30 = (Exec_v29 ∩ {π: JRC(π) ∧ RCC(π)}) ⊆ Exec_v29`。

**证明**：JR-CG 先调用 v29 的 VAD-KTCG，仅当其准入后再叠加 JRC 与 RCC 两个合取项；教师路径完全复用 v29 语义。两条路径的输出都在 `Exec_v29` 内，其并集仍 `⊆ Exec_v29`。∎

**诚实声明**：JRC 是相对特定冗余分解的**构造性**证书（可靠但不完备）；RCC 的可靠性依赖 `⊨` 证明项；`m_sem` 是估计量。三者都不是绝对安全证明，只是把 v29 的「学习组件共因失效」部分替换为「物理约束 + 规格翻译」两类可分别审计的失效面。

## 5. 实验设计（v30 验证）

**平台与基线**：MuJoCo 12-DoF 双足；地形 {平地, 斜坡, 台阶, 湿滑}，负载 {0, 10kg}，执行器含热模型。基线：v28、v29、v30、v30−JRC（去关节证书）、v30−RCC（去需求审计）。

**场景与指标**：

| 维度 | 场景 | 指标 |
|---|---|---|
| 关节可行性 | 高力矩需求（爬台阶/负载/热降额） | 关节限位违规/千步、力矩饱和率、自碰撞率、`ρ_J` 分布 |
| 需求覆盖 | 注入 5 类需求 + 3 组冲突需求 | `cov`、`m_sem` 估计 vs 人工真值、孤儿需求数、冲突漏检数 |
| 虚假绿灯 | 证书全绿但人工判定违反需求 | false-green rate（核心指标） |
| 效率 | 正常步 / 连续升级步 | 单步延迟 p50/p99、教师兜底率 |
| 漂移 | 部署中途新增/修改需求 | 陈旧窗口暴露、哈希拦截率 |

**假设**：
1. JRC 使关节限位违规下降 ≥90%、力矩饱和下降 ≥70%，代价是教师兜底率上升 ≤15%；
2. RCC 使孤儿需求数降为 0，但 `m_sem` 估计与真值之间会出现显著偏差——该偏差正是 false-green 的主因；
3. 加入 JRC 后 false-green 从「关节类」转移到「语义类」，总量下降但不会归零；
4. 快速路径覆盖 ≥80% 正常步，p99 延迟相对 v29 增加 <3ms。

**消融**：分别去掉 `⊨` 机器证明（改人工勾选）与 `m_sem` 阈值，量化 false-green 的上升幅度，直接检验「语义空洞」风险。

## 6. 已知风险与缓解（增量更新）

| 风险编号 | 描述 | 严重度 | 缓解措施 | 剩余风险 |
|---|---|---|---|---|
| R19–R27 | v29 全部既有风险 | — | 随 VAD-KTCG 原样继承 | 不变 |
| R28 | JRC 不完备：冗余分解 IK 局部极小导致假阴性，教师兜底率上升 | 中 | 1) 多 warm-start + 多初值；2) 快速路径先放行速度力矩维；3) 假阴性日志回流训练 IK 初值策略 | 极端奇异位形附近仍可能误拒，表现为可用性下降而非安全下降 |
| R29 | **需求-证书语义空洞**：`⊨` 用名义链接冒充，`m_sem` 低估，RCC 高覆盖放行规格错误系统 | 高 | 1) `⊨` 必须给出机器可检验证明项，禁止人工勾选；2) 独立人工审计真值，定期度量估计偏差；3) residual 必须显式列出并需责任人签署；4) 对未覆盖需求默认拒绝而非默认放行 | 隐性需求（用户未表达）无法被任何审计发现 |
| R30 | 需求漂移与追踪矩阵过期 | 中 | 在线 `plan_req_hash` 比对，不一致即教师路径 + 人工确认；需求变更触发全量重认证 | 变更与重认证之间的运维窗口依赖流程纪律 |
| R31 | 关节约束建模误差（热模型、摩擦、柔性）使 JRC 误放行 | 中 | 1) 力矩/温度留保守裕度；2) 在线估计摩擦与结温残差并回灌；3) 硬件在环校准 | 未建模柔性在极端冲击下仍可能越界 |

## 7. 本轮最大风险（最终确认）

**一句话**：**需求-证书映射的语义空洞**——JRC 把「关节可实现」证得很硬，但 RCC 的 `⊨` 若被名义链接填满、`m_sem` 又被低估，系统就会以高覆盖率放行一个「物理上安全、规格上错误」的执行；这是比 v29 共因失效更上游的失效，因为它发生在规格层，再完美的控制器也无法纠正一个被错误翻译的需求。
