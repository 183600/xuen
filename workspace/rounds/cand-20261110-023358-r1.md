# 第 41 轮 · 双灵感落地 v1：证书约束强化学习训练 × 证书基准测试与证伪 × 评测治理闭环（四层架构 v7）

> 承接第 40 轮（v17：可认证流匹配执行 × 度量语义几何锚定 × 证书驱动课程引擎，四层架构 v5）。本轮灵感词「强化学习训练、基准测试」把焦点从「证书如何颁发」推进到「证书如何被训练、被挑战、被信任」：将策略改进从模仿/蒸馏升级为**证书约束的强化学习**；将实验从一次性指标升级为**可证伪的证书基准**；将训练-评测边界从隐含假设升级为**可审计的治理协议**。核心命题一句话：**证书不是奖励，基准不是分数。**

## 0. 直觉与动机

**灵感 1（强化学习训练 → 从「拟合示范」到「在证书约束下探索」）**：v17 的技能来源是 IP-44 渐进蒸馏，本质是监督拟合——它能复现示教，却不能主动超越示教分布，也不会为了「修复证书赤字」而去探索。IP-50 课程已经知道哪里薄弱（证书赤字最高），但它手里没有改进算子：知道哪里差，不等于能把差变好。RL 正是这个缺失的改进算子。然而，**把证书边际直接塞进奖励是危险的**：策略会学会寻找证书估计器的乐观区（reward hacking），把「看起来安全」当成「真的安全」。正确做法是把证书当**约束**（CMDP / primal-dual）而不是奖励，且约束的度量必须来自**不参与梯度**的独立审计器。第二个更隐蔽的陷阱是 shield：训练时用 CBF-QP 投影保证安全，会让策略永远见不到近违约状态，证书只在被 shield 过滤后的分布上被验证——**看起来完美，实则 off-support**。因此必须认证的是**复合策略** Π∘π，必须做 shield 课程与 shield-off 影子评测，并用重要性权重校正选择偏差。

**灵感 2（基准测试 → 从「跑分」到「证伪」）**：v17 的 E67–E72 是自证式实验：用自己的指标验证自己的证书，缺少独立、对抗、可复现的证书基准。基准测试的第一性原理不是排榜，而是**可证伪性**：一个好的证书基准应当主动寻找反例，而不是在训练分布上取平均。于是引入**证书证伪器**（falsifier）——在证书声称安全的 ValidRegion 内部搜索违约，而不是在训练集上刷成功率。基准必须同时测四个维度：soundness（声称安全时真的安全吗）、tightness（界松多少）、discrimination（证书边际能否区分失败）、coverage（ValidRegion 覆盖多少真实部署）；再加上 contamination（训练/评测泄漏）。而且基准本身会饱和、会被污染、会被 Goodhart，所以必须 proxy/sealed 双轨、污染审计与基准退役。

**灵感 3（二者耦合 → 训练/认证/评测的「三权分立」）**：训练器（IP-54）优化任务与证书约束；审计器（RCA，独立数据）颁发与重颁证书；基准（IP-55）只负责证伪，不参与训练；治理器（IP-56）维持三者隔离，检测 proxy-sealed 分歧与证书泄漏。核心原则是：**任何被优化的证书都会退化；只有被独立挑战、且挑战者无法被优化的证书才可信。** 因此训练永远看不到 sealed benchmark，证书审计器永远不进入梯度，基准只把「反例」以脱敏形式路由给治理器，而不把分数反馈给课程。

**三灵感的耦合**：RL 给出「在约束下变强」的算子，基准给出「证书是否真的可信」的判据，治理给出「变强没有作弊」的制度保障。v17 解决的是「证书怎么写」，本轮解决的是「证书凭什么值得信」。

## 1. 形式化定义

**定义 27（证书约束马尔可夫决策过程 Cert-CMDP）**：M = (S, A, P, r_task, γ, {C_i}, {ε_i}, ValidRegion)。第 i 类证书成本定义为边际违约量 C_i(s,a) = max(0, c_i − m_i(s,a))，其中 m_i 沿用定义 26 的六类实测边际。优化目标：

  max_π J_r(π)  s.t.  J_{C_i}(π) ≤ ε_i (∀i)，且 supp(π) ⊆ ValidRegion(C)。

拉格朗日形式 L(π,λ) = J_r − Σ_i λ_i (J_{C_i} − ε_i)，primal-dual 更新 λ_i ← [λ_i + η_λ (J_{C_i} − ε_i)]_+。证书约束**只在 ValidRegion 内定义**；出区进入 absorbing failure 状态，代价记为 C_out，防止策略利用「激光未覆盖 / 漂移球外」的空白区刷分。

**定义 28（复合策略与 shield 证书）**：部署策略为 π̄ = Π_β ∘ π，Π_β 是在安全预算 β 内的 CBF-QP / 证书投影算子。
- **命题 1（收缩继承）**：若 Π_β 在凸约束下为 firmly nonexpansive，且流速度场 v_θ 为 κ-收缩，则复合流映射 φ̄ = Π_β ∘ φ 满足 ‖φ̄(x) − φ̄(y)‖ ≤ ‖φ(x) − φ(y)‖ ≤ e^{−κT}‖x − y‖。即 CertFlow 的 κ 可直接继承，但 ε_ode 必须叠加每步投影扰动 ε_Π：ε_ode^Π(N) = ε_ode(N) + (1 − e^{−κT})/κ · max_t ε_Π(t)。
- **命题 2（shield 选择偏差）**：设 D_shield 为 shield 开启时的状态分布、D_deploy 为部署分布。若 β 使 P(近违约带 | D_shield) ≪ P(近违约带 | D_deploy)，则基于 D_shield 的违约率估计是 D_deploy 的**乐观下界**。无偏估计需用重要性权重 w = dD_deploy/dD_shield，或用 shield-off 影子 rollout 校正。
- **Shield 课程**：β(t) 三段式「强 → 弱 → 部署强度」。强段安全冷启动，弱段专门采集边界数据供审计，末段回到部署强度；边界数据只进审计器，不进训练梯度。

**定义 29（证书边际优势与悲观证书评论器）**：Q_cert^π(s,a) = E_π[Σ_t γ^t m(s_t,a_t) | s₀=s, a₀=a]，A_cert = Q_cert − V_cert。训练奖励只做 shaping：r_train = r_task + λ_s · m̂_lcb，其中 m̂_lcb 为证书评论器 ensemble 的 (1−δ) 下分位；当 ensemble 方差 > τ（off-support）时改用悲观值 m_min。**评论器可训练、可进梯度；审计器 held-out、只用于颁发与证伪**，二者数据不相交。

**定义 30（证书基准 B 与四维效度）**：B = {(τ_i, Δ_i)}，Δ_i 为分布偏移族（光照/材质/动力学/传感器退化）。对证书 C 定义五项：
- **Soundness**：V_sound = P_{x∼D_deploy}(violation | C(x)=safe) ≤ δ_claim；
- **Tightness**：ρ_tight = E[bound / empirical margin]；
- **Discrimination**：AUROC(m̂(x), 1[fail(x)])；
- **Coverage**：P_{x∼D_deploy}(x ∈ ValidRegion)；
- **Contamination**：overlap(B_train, B_sealed) 与 proxy-sealed 性能差。
一个基准条目合格需同时满足**预先注册**（pre-registration）的阈值，而不是单一成功率。

**定义 31（证书证伪器 Falsifier）**：证伪器 A 在「证书声称安全」的区域内部最大化违约：

  max_{δ : x+δ ∈ ValidRegion} P(fail | x+δ) − λ · dist(δ)。

实现为三路并集：对可微仿真用梯度引导对抗扰动，对不可微环境用进化搜索，对长时程用 RL 红队（reward = 违约，action = 状态/参数扰动）。反例进入 counterexample set X_ce，只用于（a）重颁证书、（b）人工审查、（c）安全修复数据，**绝不进入 sealed 评分**。

**定义 32（评测治理与封印协议）**：三元分离 (Trainer T, Auditor A, Benchmark E)。治理器 G 维护：
- **封印**：E_sealed 对 T 与课程不可见，仅 G 在验收时查询；
- **污染审计**：near-duplicate / 轨迹指纹 / 「训练步数-性能」相关性检验；
- **泄漏检测**：Δ_leak = trend(|m̂_A − m̂_T|)，超阈即冻结证书；
- **基准退役**：proxy 饱和（success > 95% 且 discrimination < 0.6）→ 退役并提升 Δ 难度；
- **晋升**：任务只有在 proxy 上稳定且证伪器无新反例，才可进入 sealed 验收。

## 2. 三大产出设计

### 2.1 IP-54 CERTIFIED-RL-TRAINER（证书约束强化学习训练器）
1. **Cert-CMDP 求解器**：PPO 主目标 + 每类证书边际一个 λ_i 的 primal-dual；成本只在 ValidRegion 内计费，出区 absorbing failure；Slater 条件与步长条件下收敛到 ε-约束可行域。
2. **Shield 课程**：β 三段式（强→弱→部署）；弱段专采边界数据；shield-off 影子 rollout 做无偏审计；用重要性权重校正选择偏差。
3. **悲观证书评论器**：ensemble + LCB shaping；off-support 检测（方差/密度）；评论器与审计器数据隔离、参数隔离。
4. **改进算子接口**：IP-50 课程给出证书赤字最高的任务带 → IP-54 在该带做 RL 修复 → IP-46 重颁证书 → IP-45 契约热更新。
5. **防奖励黑客**：约束用独立审计器；shaping 用 LCB；对 m̂ 做 randomized smoothing / 随机审计；sealed 数据禁止进入梯度。

### 2.2 IP-55 CERT-BENCH（证书基准测试与证伪）
1. **二维基准矩阵**：按证书边际 m 分桶（安全/边界/超界）× 按 Δ 分布偏移族交叉，避免只在「平均难度」上自证。
2. **四维效度指标**：soundness / tightness / discrimination / coverage + contamination，阈值预先注册，基准版本 append-only 不可回改。
3. **三路证伪器**：梯度对抗 + 进化搜索 + RL 红队；反例去重、最小化（delta-debugging）后形成 counterexample set。
4. **证书有效性卡**（Certificate Validity Card）：像 model card 一样记录适用范围、失效场景、置信度、审计数据版本、已知反例。
5. **封印协议**：sealed / proxy 双轨；near-duplicate 指纹；sealed 只由治理器在验收时打开。

### 2.3 IP-56 EVAL-GOVERNED LOOP（评测治理闭环）
1. **分歧监测**：proxy 与 sealed 的 success/margin 差、AUROC 差；超阈判定 benchmark overfitting。
2. **泄漏检测**：审计器 vs 训练器 m̂ 的 gap 趋势；这是证书退化为「装饰性文档」的前兆信号。
3. **反例路由**：证伪器的反例分三类——证书错（重颁）、基准错（退役/修正）、真失败（安全修复数据），三路分离。
4. **课程只接 proxy + 脱敏反例信号**；sealed 永不反馈；定期盲测。
5. **退役与晋升**：饱和即退役并提升难度；新任务需证伪器无新反例才晋升。

## 4. 实验设计（E79–E84 硬门槛）

| 实验 | 指标 | 门槛 |
|---|---|---|
| E79 约束下 RL 改进 | 边界任务成功率 vs 纯模仿；证书违约 | 提升≥15%；违约≤ε |
| E80 shield 迁移与偏差 | shield-off vs on 差距；重要性校正误差；复合证书有效性 | 差距≤10%；校正误差≤20%；有效性≥99% |
| E81 奖励黑客 | 策略利用审计器乐观区的比率；LCB 后下降 | 下降≥50%；审计-训练边际 gap≤0.1 |
| E82 基准效度 | soundness 违约率、tightness 比、AUROC、coverage | ≤δ；≤3；≥0.9；≥90% |
| E83 证伪器效力 | 每千次查询反例数；修复后攻击下违约下降 | ≥5 个；下降≥70% |

## 5. 本轮最大风险

**一句话**：整套方案悬于「训练器 / 审计器 / 基准」三者能否真正独立——若它们共享同一仿真器、同一 LIO 与同一证书估计器（在本架构中几乎是默认事实），则 sealed 基准会泄漏、审计器会与策略共适应，RL 将优化出一个自洽的幻觉，证书看起来越来越可信而部署越来越危险，故 E81/E84 必须作为本轮第一守门实验。

| A_falsify | 证书证伪器 | max_{δ:x+δ∈ValidRegion} P(fail|x+δ) − λ·dist(δ) |

| E_sealed / E_proxy | 封印/代理基准 | sealed 对训练器与课程不可见 |
| Δ_leak | 泄漏指标 | trend(|m̂_A − m̂_T|)，超阈冻结证书 |

## 2. 关键算法

### IP-54 证书约束 RL 训练（伪代码）
```
def cert_cmdrl_train(policy, env, auditor, critic, lagr, shield_sched):
    for it in range(N_iter):
        beta   = shield_sched(it)                     # 强 -> 弱 -> 部署
        traj   = rollout(policy, env, shield=Pi_beta,
                         valid_region=env.VR)          # 出区=absorbing failure
        # (1) 成本只用独立审计器，不进梯度
        J_c    = auditor.estimate_costs(traj)          # {J_{C_i}}
        # (2) shaping 只用悲观评论器，禁止用证书上界当奖励
        m_lcb, unc = critic.ensemble_lcb(traj)
        r_shape = where(unc < tau, m_lcb, m_min)
        adv    = ppo_advantage(traj.r_task + lam_s * r_shape, traj.values)
        policy.update(adv)
        # (3) primal-dual 约束更新
        for i in range(K):
            lagr.lam[i] = max(0, lagr.lam[i] + eta_l * (J_c[i] - eps[i]))
        # (4) shield-off 影子审计（无梯度）
        if it % audit_period == 0:
            auditor.reaudit(policy, shield_off=True, iw=importance_weight)
        if leak_detected(auditor, critic):
            freeze_certificate(); alert("auditor-critic co-adaptation")
```

### IP-55 证书基准与证伪（伪代码）
```
def cert_bench(cert, policy, suite):
    card = CertificateValidityCard(version=suite.version)
    for (task, shift) in suite.matrix:                 # 边际桶 × 偏移族
        roll = evaluate(policy, task, shift, shield=False)   # 部署复合策略
        card.soundness    = violation_rate(roll, cert)
        card.tightness    = mean(cert.bound / empirical_margin(roll))
        card.discrimination = auroc(cert.margin, roll.fail)
        card.coverage     = frac(roll.states in cert.ValidRegion)
    ce = union(falsify_grad(cert, suite),
               falsify_evo(cert, suite),
               falsify_rl_redteam(cert, suite))        # 三路证伪
    card.counterexamples = minimize_and_dedup(ce)      # delta-debugging
    card.contamination   = audit_overlap(suite.train, suite.sealed)
    return card                                        # 阈值预先注册，append-only
```

### IP-56 评测治理闭环（伪代码）
```
def eval_governor(proxy, sealed, auditor, trainer, bench, falsifier):
    gap  = divergence(proxy.metrics, sealed.metrics)
    leak = trend(abs(auditor.margin_hat - trainer.margin_hat))
    if gap > tau_gap or leak > tau_leak:
        freeze(cert); alert("benchmark overfitting / certificate leakage")
    for ce in falsifier.counterexamples:
        cause = classify(ce)               # cert_bug | bench_bug | real_failure
        if   cause == "cert_bug":  RCA.reissue(cert)
        elif cause == "bench_bug": bench.retire_or_fix(ce)
        else:                      safe_repair_data.add(ce)   # 绝不进 sealed
    if proxy.saturated():          # success>95% 且 AUROC<0.6
        bench.retire_and_escalate(shift_family)
    if proxy.stable() and not falsifier.new_counterexample():
        bench.promote(task)        # 晋升到 sealed 验收
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 正确性保证 |
|---|---|---|
| Cert-CMDP 训练 | O(N_iter·|traj|·(|A|+K)) | Slater + 步长条件下依概率收敛到 ε-约束可行域 |
| Shield QP | 每步 O(d_a³) | Π_β firmly nonexpansive ⟹ 复合映射继承 κ-收缩；ε_ode 加 ε_Π |
| 重要性校正 | O(|traj|) | w=dD_deploy/dD_shield 无偏（support 覆盖时）；否则给偏差上界 |
| 证书评论器 | 每查询 O(E·d) | ensemble LCB 给 (1−δ) 悲观下界；off-support 检测 |
| 证伪器 | 梯度 O(d)/步；进化 O(pop·gen)；红队 RL | 非完备搜索：只保证「找到即反例」，不保证找全 |
| 基准评估 | O(|B|·|Δ|·rollouts) | 四维指标 + 预先注册阈值，避免事后挑选 |
| 污染/泄漏检测 | O(n log n)（指纹去重） | near-duplicate 召回；Δ_leak 趋势检验 |
| 治理路由 | O(|X_ce| log|X_ce|) | 反例三分类 + 三路隔离 |

## 4. 实验设计（E79–E84，硬门槛）

| 实验 | 指标 | 门槛 |
|---|---|---|
| E79 约束下 RL 改进 | 边界任务成功率 vs 纯模仿；证书违约率 | 提升≥15%；违约≤ε |
| E80 shield 迁移与偏差 | shield-off vs on 差距；重要性校正误差；复合证书有效性 | 差距≤10%；误差≤20%；有效性≥99% |
| E81 奖励黑客 | 利用审计器乐观区的比率；LCB 后下降；审计-训练 gap | 下降≥50%；gap≤0.1 |
| E82 基准效度 | soundness、tightness、AUROC、coverage | ≤δ；≤3；≥0.9；≥90% |
| E83 证伪器效力 | 每千查询反例数；修复后攻击下违约下降 | ≥5；下降≥70% |
| E84 污染与治理 | 注入泄漏召回；proxy-sealed 分歧 AUC；退役触发率 | ≥90%；≥0.9；100% |

失败即回退：E79/E81 不达标 → 证书不作训练信号，RL 降级为离线数据增强；E82/E83 不达标 → 回退 v17 自证式实验，CERT-BENCH 转离线分析工具；E84 不达标 → 强制单轨盲测，禁用自动晋升。

## 5. 风险与缓解

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 训练器/审计器/基准共享仿真器与 LIO → 独立性名存实亡 | 高 | 审计数据版本隔离 + 影子 shield-off 审计 + 随机审计 + E84 第一守门 |
| 证书被当奖励 → reward hacking / 乐观区利用 | 高 | 证书只作约束；shaping 用 LCB；禁止 sealed 进梯度；E81 守门 |
| shield 选择偏差 → 证书在 off-support 上虚高 | 高 | 认证复合策略；shield 课程；重要性权重；E80 守门 |
| 基准饱和/污染/事后挑指标 | 中 | 预先注册 + append-only + sealed/proxy + 退役机制 |
| 证伪器不完备 → 漏掉真实失效模式 | 中 | 三路并集 + 覆盖度审计；把「未找到反例」表述为证据而非证明 |
| CMDP 多约束不可行 / λ 振荡 | 中 | 约束预算分层 + 松弛变量 + 双时间尺度 λ |
| 基准退役过快 → 失去难度梯度 | 低 | 退役与晋升成对，保留历史版本做纵向对比 |

## 6. 本轮最大风险

**一句话**：整套方案悬于「训练器 / 审计器 / 基准」三者能否真正独立——若它们共享同一仿真器、同一 LIO 与同一证书估计器（在本架构中几乎是默认事实），则 sealed 基准会泄漏、审计器会与策略共适应，RL 将优化出一个自洽的幻觉，证书看起来越来越可信而部署越来越危险，故 E81/E84 必须作为本轮第一守门实验。
