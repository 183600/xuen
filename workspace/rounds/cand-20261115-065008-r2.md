# 第 4 轮（灵感循环第 4 轮；本轮灵感：「成功率」×「服务设计」）

> **基线**：第 3 轮 InstructGauge（IP-321–327；定义 432–447；引理 51–58；实验 E441–E456）。第 1/2 轮 LeanGauge、ToolGauge / MODGAUGE 骨架继续继承不变。
> 本轮纪律：**只加度量与承诺层，不加物理能力**。新层是纯统计/审计投影；任一环节不可用即可整体退回 InstructGauge 的指标口径，50Hz 物理闭环不动。

## 0. 直觉与动机

**灵感 1（成功率 → 不是「完成率」，而是带删失与竞争风险的「服务水平」）**
直觉：现场工程师真正问的不是「你跑了几次、成功几次」，而是「在我给的**时间视界 τ** 与**预算 B** 内，你把这块盲区测到可用精度的概率有多大」。把成功率当普通比例会犯三个错：(a) 只统计跑完的 episode，丢掉超时/中断的（幸存者偏差）；(b) 把「安全中止」「预算耗尽」「超时」全折叠成失败，丢失可修复性信息；(c) 运维是边看仪表盘边决定停不停的（peeking），固定样本置信区间因此失效。所以成功率必须定义成**条件于场景类、带 τ 与 B、由竞争风险累积发生率给出**的量，并配**任意时有效（anytime-valid）置信序列**。

**灵感 2（服务设计 → 前台承诺必须由后台证据兜底）**
直觉：服务设计的核心不是界面，而是**前台—后台—支持过程**的服务蓝图，以及「前台对用户承诺什么」与「后台能否交付」之间的对齐。把盲区修复当成一项「计量服务」后，InstructGauge 已有的 receipts / ChunkCert / claims 恰好就是后台证据；但现有设计允许前台说「已修复」，而后台只保证「某一层覆盖 1−α」，二者之间存在**承诺—证据错位**。服务设计给出的硬约束是：**承诺只能被证据支配（promise ⪯ evidence），且只降不升**——证据不足就降级措辞与数值，绝不美化证据。

**灵感 3（耦合 → 成功率是 SLO，必须可审计、可防 Goodhart）**
直觉：一旦「成功率」被写进服务合约，它立刻变成会被优化的指标：多删失一点、分层细一点、超时阈值松一点，数字都能变好看。正确做法不是「优化成功率」，而是**在固定 SLO 下优化服务容量与恢复能力**，同时用 e-process 把「报喜不报忧」的操纵变成可检测的统计异常。成功率于是从「结果指标」升级为「合约对象 + 完整性约束」。

## 1. 研究问题（本轮要回答什么）

- **Q1（度量的诚实性）**：如何定义并估计一个对删失、竞争风险与自适应停止都稳健的服务级成功率？
- **Q2（承诺的对齐性）**：如何保证面向人的前台承诺永不超过后台证据的可证下界？
- **Q3（服务的经济性）**：给定 SLO 时，成功率与容量（到达率/服务时间/排队）之间可证的权衡是什么？成功率被当 KPI 后如何防 Goodhart？

## 2. 三条设计原则（正式化见产物区定义 448–460）

**P1 删失即信息（Censoring-as-Evidence）**
任何未完成的 episode 都不得被丢弃，必须以右删失或竞争风险进入估计；报告必须给出累积发生率口径与风险集，而不是「成功数 / 完成数」。这是对 InstructGauge 完成率口径的统计修正。

**P2 承诺只降不升（Promise-Only-Down）**
前台承诺由其后台证据的**下界**决定；证据不足时只允许降级承诺（更弱的措辞、更低的数值、更长的延迟上界），禁止反向「上调证据」。这把服务蓝图变成可机检的不变式。

**P3 成功率是约束不是目标（SR-as-Constraint）**
不直接把 SR 当优化目标；在 `SR ≥ s₀` 的服务约束下最大化容量、最小化每成功成本，并用 e-process 检测指标操纵。避免「为指标而指标」的 Goodhart 陷阱。

## 3. 与基线的接口（如何退化）

- 无删失、无竞争风险 ⇒ CSR 退化为二项完成率（InstructGauge 口径）；
- 无自适应停止 ⇒ 任意时有效 CS 退化为固定视界 CI；
- 无策略切换 ⇒ IPW/DR 退化为分层直接平均；
- 无服务合约 / 无需面向人 ⇒ 关闭 PEA，SR-Cert 只做描述统计；
- 任一环节不可用 ⇒ 回到 InstructGauge 指标；物理闭环始终继承 ToolGauge 退化链。

## 4. 预期贡献

1. 一个竞争风险 + 删失感知的**服务级成功率**定义与估计器（CSR），消除「只算跑完的」偏差；
2. 一个**任意时有效置信序列**，支撑「边看边停」的真实运维；
3. 一个**服务蓝图 + 承诺-证据对齐（PEA）**审计口径，杜绝未背书的 SLA；
4. 一个 **off-policy 成功率估计**（IPW/DR）与**成功率预算准入**（SRA），把成功率与容量/SLO 连起来；
5. 一个 **Goodhart 完整性 e-process**，把指标美化变成可检测异常；
6. 一条可证伪路径 E457–E472。

## 5. 本轮最大风险

**一句话**：成功率一旦成为服务合约的门面指标，系统就有强激励通过「多删失、细分层、放宽视界」来美化数字，而 PEA 与 e-process 只能**检测**、不能**消除**这种激励——真正的残余风险是「SLO 剧场」：一个统计上诚实、服务上却无效的成功率。

## 2. 形式化定义（要点）

**定义 448（服务合约 SLO）** `SLO = (z, q, τ, B, α, Safe)`。episode `e` 在第 `t₀` 到达；成功指示
`Y_e = 1[ w_{T_e}(e) ≤ q ∧ T_e ≤ τ ∧ cost_e ≤ B ∧ ¬SA_e ]`，
其中 `w_t` 为时刻 `t` 的测量不确定度（取共形区间半宽），`T_e` 为停止时间。关键：成功是**联合事件**，`SLO` 是对人的合约而非事后统计。

**定义 449（竞争风险 episode 与观测）** 完全观测为 `(T_e, J_e)`，`J_e ∈ {S,TO,AB,SA,CN}`；实际只看到 `(T_e^obs, J_e^obs)`。`J_e=CN` 为右删失（仍在运行/被外部中断）。假设**给定 `(z,s)` 条件独立删失**；若该假设不可检，则退化为最坏界（引理 59/60）。

**定义 450（服务级成功率）**
`SR(τ|z) = P(T_e ≤ τ, J_e = S | z) = F_S(τ|z)`，
即成功作为竞争风险的**累积发生率**，而非 `P(S | completed)`。两者一般不等；后者在删失依赖结果时有偏。

**定义 451（任意时有效置信序列）** 对成功指示的有界序列 `Y_1,Y_2,…∈{0,1}`，`CS_t=[L_t,U_t]` 满足 `P(∀t≥1: SR ∈ CS_t) ≥ 1−α`。由混合鞅构造：
`M_t(θ)=∫ ∏_{u≤t}(1+λ(θ,u)(Y_u−θ)) dπ(λ)`，反演 `{θ: M_t(θ)<1/α}` 得 `CS_t`。对任意停时可选的停止规则仍有效。

**定义 452（服务蓝图 SB）** `SB=(front, back, support, F, R)`：`front` 为用户可感知接触点（指令、解释、仪表盘、告警）；`back` 为 probing / 校准 / 契约更新；`support` 为回执库、共形校准集、证据存储；`F` 为失败点（接地失败、块截断、跨校准、SLO 违约）；`R` 为每类失败点的恢复动作与目标 MTTR。

**定义 453（承诺-证据对齐 PEA）** 对前台承诺 `p` 与后台证据 `e`：
`PEA(p,e) ⟺ claim_success(p) ≤ L_t(e) ∧ claim_cov(p) ≤ 1−α_e ∧ claim_latency(p) ≥ U_t(latency(e))`。
系统不变式：`∀p∈front, ∃e∈support: PEA(p,e)`。违约 ⇒ `downgrade(p)`（降低承诺），**永不** `upgrade(e)`。

**定义 454（分层与选择校正）** `s=stratum(x)`，`e_s(x)=P(S=s|x)` 为分配倾向。目标策略 `π'` 下的服务成功率
`SR_{π'} = E[ (π'(s|x)/e_s(x)) · Y ]`（IPW），或
`SR_DR = E[ m_{π'}(x) + (π'(s|x)/e_s(x))(Y − m(s,x)) ]`（双重稳健）。
要求正性 `inf_x e_s(x) > 0`；报告 `ESS=(Σw)²/Σw²` 作为可信度诊断。

**定义 455（成功率预算准入 SRA）** 到达请求 `x` 时，估计准入的边际收益
`ΔSR(a|x) = SR(τ|x, a=1) − SR(τ|x, a=0)`。
准入当且仅当 `ΔSR ≥ 0`、`ρ = λ·E[T_srv] < 1 − ε_headroom`、`cost(a) ≤ B_srv − B_used`、且 `SR_LB(x) ≥ s₀`（SLO 下界）。这把成功率变成**预算约束**而非目标函数。

**定义 456（容量—SLO 前沿）** 在到达率 `λ`、服务率 `μ`、排队等待 `W` 下，可持续成功率近似
`SR*(ρ) ≈ (1 − P(W > τ)) · p_srv`，`ρ=λ/μ`。当 `ρ→1` 时 `P(W>τ)→1`，`SR*→0`。故给定 SLO 下界 `s₀` 存在最大可持续利用率 `ρ*(s₀)`，构成容量规划依据。

**定义 457（Goodhart 完整性 e-process）** 检验 `H₀: SR ≥ SR_claim`（声称是诚实的）对 `H₁: SR < SR_claim`。固定替代 `μ₁<SR_claim`，似然比
`M_t = (μ₁/SR_claim)^{S_t} · ((1−μ₁)/(1−SR_claim))^{t−S_t}`。
`H₀` 下 `M_t` 为超鞅；真实为 `μ₁` 时 `E[log M_t] = t·KL(μ₁‖SR_claim)`。当 `M_t ≥ 1/α` 拒绝「诚实声称」。检测时间 `O(log(1/α)/KL)`。

**定义 458（服务证书 SRCert）** `SRCert(e) = (SLO, z, SR_hat, CS_t, SB, PEA-audit, propensity/ESS, M_t, degrade_flags)`。它把「成功率」从单点数字变成可审计对象：任何对外数字都必须携带其估计口径、覆盖保证、分层与删失处理、以及完整性证据。

**定义 459（审计投影的纯性）** CSR、CS、PEA、OPE、SRA、integrity 均为**只读或准入类**投影：不改变 `Γ`、不改变分块、不改变物理动作序列；唯一影响执行的 SRA 是**拒答**（等于不提交），不产生新的动作能力。故所有安全引理（51/52/56/57）原样继承。

**定义 460（退化映射）** 令 `G` 为 ServGauge 配置：`G=∅`（关闭全部新层）⇒ 输出与 InstructGauge 逐字段一致；仅开 CSR ⇒ 完成率换成 CIF；仅开 CS ⇒ 区间变任意时有效；仅开 PEA ⇒ 增加承诺降级；仅开 SRA ⇒ 增加准入拒答。退化是**逐层可交换**的，且每层失败只损失其自身保证。

# IP-328 SLO 合约编译：成功是联合事件
def compile_slo(z, q, tau, B, alpha, floor):
    return SLO(z=z, q=q, tau=tau, B=B, alpha=alpha, safe=True, floor=floor)

# IP-329 CSR：竞争风险累积发生率（Aalen–Johansen）
class CSR:
    def fit(self, episodes):                 # (T_obs, event_type, z, s, x)
        self.cif = aalen_johansen(episodes)   # 全因风险集 + 成功 CIF
    def sr_at(self, tau, z):
        return self.cif[z].eval(tau)          # F_S(tau | z)
    @staticmethod
    def naive(episodes):                      # 有偏基线，仅用于对照
        done = [e for e in episodes if e.completed]
        return sum(e.success for e in done) / max(len(done), 1)

# IP-330 任意时有效置信序列（混合鞅）
class AnyValCS:
    def __init__(self, alpha):
        self.alpha, self.log_mix, self.n = alpha, 0.0, 0
    def update(self, y):
        self.n += 1
        self.log_mix = logaddexp(self.log_mix, self._log_bet(lambda_, y))
    def interval(self):
        return invert_mixture(self.log_mix, alpha=self.alpha)  # [L_t, U_t]

# IP-331 服务蓝图 + 承诺-证据对齐审计
def pea_audit(blueprint, evidence, cs):
    bad = []
    for p in blueprint.front:
        e = evidence.match(p)
        ok = (e is not None
              and e.success_lb >= p.claim_success          # 承诺 ≤ 证据下界
              and e.coverage >= p.claim_cov
              and e.latency_ub <= p.claim_latency)
        if not ok:
            bad.append(p)
    return bad                                          # 违约承诺 → 只降不升

# IP-332 off-policy 成功率（IPW / DR + ESS 诊断）
def sr_off_policy(log, pi_new, pi_old):
    w = [pi_new(s, x) / max(pi_old(s, x), EPS) for (s, x, y) in log]
    ipw = sum(wi * y for wi, (_, _, y) in zip(w, log)) / len(log)
    dr  = ipw + regression_residual(log, w)
    ess = (sum(w) ** 2) / max(sum(wi ** 2 for wi in w), EPS)
    return ipw, dr, ess

# IP-333 成功率预算准入（不优化 SR，只在 SLO 下准入）
def admit(req, model, queue, slo):
    d   = model.delta_sr(req)                    # 预测边际成功率收益
    rho = queue.lam * queue.mean_service_time
    return (d >= 0 and rho < 1 - HEADROOM
            and model.cost(req) <= slo.B - model.budget_used()
            and model.sr_lower(req) >= slo.floor)

# IP-334 Goodhart 完整性检验
class Integrity:
    def __init__(self, alpha):
        self.M, self.alpha = 1.0, alpha
    def update(self, success, claim, mu1):
        p1   = mu1 if success else 1 - mu1
        p0   = claim if success else 1 - claim
        self.M *= p1 / p0
        return self.M >= 1.0 / self.alpha        # 拒绝「诚实声称」

# IP-335 ServGauge-8C：物理闭环外包一层异步服务审计
def servgauge_8c(M, req):
    if not admit(req, M.model, M.queue, M.slo):
        return SKIP                               # 拒答 ≠ 执行新动作
    out  = instructgauge_7c(M, req.spot, req.ell) # 物理路径完全不变
    e    = M.episodes.record(req, out)
    M.csr.fit_incremental(e)
    M.cs.update(1 if out.success else 0)
    if pea_audit(M.blueprint, M.evidence, M.cs.interval()):
        M.promises.downgrade()                    # 只降承诺
    if M.integrity.update(out.success, M.promises.sr_claim, M.mu1):
        M.promises.revoke("integrity"); alert()   # 可检测的指标操纵
    return SRCert(M.slo, M.csr.sr_at(M.slo.tau, req.z), M.cs.interval(),
                  M.blueprint, M.pea.last_audit, M.ess, M.integrity.M,
                  M.degrade_flags())

# IP-336 主闭环：50Hz 物理路径原样
def ServGauge_round(M, obs, audio, tac, depth, det, ell=None):
    for req in M.dbox.pending_requests():
        submit_async(servgauge_8c, M, req)        # 异步；不阻塞 50Hz
    return MODGAUGE_round(M, obs, audio, tac, depth, det)

## 4. 推导

**引理 59（完成者偏差界）** 设 `p=SR_true`，完成指示 `C`，`P(C|Y=1)=1`、`P(C|Y=0)=c<1`（失败更易被删失/超时）。则
`SR_naive = p / (p + (1−p)c) ≥ p`，且偏差 `SR_naive − p = p(1−p)(1−c)/(p+(1−p)c) → 1−p`（当 `c→0`）。
*证明*：条件概率展开即得。故「只算跑完的」系统性高估，且高估幅度随删失率上升可任意大（`c→0` 时趋于 `1−p`）。

**引理 60（Aalen–Johansen 一致性）** 在给定 `(z,s)` 条件独立删失且风险集正性下，`F̂_S(τ|z)` 相合且渐近正态；而 `SR_naive` 仅在 `C ⫫ Y` 时相合，否则收敛到 `P(Y=1|C) ≠ P(Y=1)`。
*证明骨架*：计数过程分解 `N_S = N_S^* + 编译噪声`，删失鞅与成功鞅正交；AJ 是 `∫ dN_S/Y` 的乘积积分估计，标准鞅中心极限定理给出结论。naive 是 `N_S(τ)/N_C(τ)`，其极限由 `P(C|Y)` 决定。

**引理 61（任意时有效覆盖及其代价）** 混合鞅 `CS_t` 对任意停止规则满足 `P(∃t: SR∉CS_t) ≤ α`；其宽度几乎必然为 `O(√(log log n / n))`，而固定视界 CI 为 `O(1/√n)`。代价仅一个 `√(log log n)` 因子，不存在额外的「peeking 税」；固定 CI 在 peeking 下覆盖可趋于 0。
*证明*：`M_t(θ)` 为非负超鞅，Ville 不等式给出任意时有效性；宽度由混合分布尾部与鞅偏差的逆用给出。

**引理 62（PEA 的保真：不会过度承诺）** 若每个前台承诺 `p` 都被某证据 `e` 支配（PEA），且 `CS_t` 在 `1−α` 下覆盖真值，则用户观测到的成功率承诺不超过真实下界：`claim_success(p) ≤ L_t(e) ≤ SR`，失败概率 `≤ α`。
*证明*：`PEA` 给出 `claim ≤ L_t`，`CS` 给出 `L_t ≤ SR`（以 `1−α` 概率），串联即得。故系统「过度承诺」的概率被 CS 的覆盖水平直接夹住。

**引理 63（off-policy 成功率识别与方差）** 在无混淆分配与正性下，`SR_IPW` 无偏，`Var = (1/n)(E[w²Y] − SR²)`，`w=π'/e`；`ESS=(Σw)²/Σw²` 决定有效样本量。`SR_DR` 在倾向模型或结果模型**任一正确**时相合，且方差不超过 IPW 的一阶项。
*证明*：IPW 的期望展开用 `E[π'(s|x)/e(s|x) | x] = 1`；DR 是增广 IPW 的一阶残差零均值性；方差由独立性求和。

**引理 64（SRA 的长期单调性与稳定性）** 在流体极限下，若每次准入满足 `ΔSR ≥ 0`，则长期成功率关于准入数单调不降；但若 `ρ = λ·E[T_srv] ≥ 1`，队列发散，等待 `W→∞`，`P(W>τ)→1`，故 `SR*→0`。因此维持 SLO 下界 `s₀` 必须 `ρ ≤ ρ*(s₀) < 1`。
*证明*：单调性由逐次非负增量求和；稳定性由 Lindley 递推/排队论给出 `W` 的尾概率随 `ρ→1` 爆炸，代入定义 456 得结论。

**引理 65（Goodhart 可检测性）** 若持续声称 `SR_claim > SR_true`，取 `μ₁=SR_true`，则 `E[log M_t] = t·KL(SR_true‖SR_claim) > 0`，故 `M_t` 以高概率在 `t = O(log(1/α)/KL)` 内越过 `1/α`。反之，若声称诚实（`SR_claim ≤ SR_true`），`M_t` 为超鞅，误报率 `≤ α`。
*证明*：Bernoulli 对数似然比的和即 KL 散度；`H₀` 下非负超鞅 + Ville 不等式；替代下强大数律给出线性增长。

**引理 66（层叠退化等价）** 当 `G=∅`（关闭 CSR/CS/PEA/OPE/SRA/integrity）时，ServGauge 的物理动作序列与 InstructGauge **逐指令相同**（`SRCert` 仍可输出描述统计）；50Hz 内联开销不变。开启任意子层只增加对应的统计/审计保证，不改变动作序列（SRA 仅可能**减少**提交，不新增动作）。
*证明*：所有新层读写的是 episode 日志与证据库，物理调用点仍只有 `instructgauge_7c`；由定义 459 的纯性与归纳即得。递减链回到 InstructGauge 引理 57、ToolGauge 引理 49、第 1 轮引理 44。

## 8. 本轮最大风险

**一句话**：`成功率`作为服务合约的门面指标会诱导「SLO 剧场」——通过多删失、细分层、放宽 `τ` 让数字好看；`PEA` 只能保证承诺不超过**当前证据**，`e-process` 只能**事后检测**操纵，二者都无法消除「指标可被选择性地定义」这一激励，真正的残余风险在服务治理而非统计本身。
