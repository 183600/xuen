# 第 1 轮灵感札记：用「角色一致性」与「基线复现」修补 v23 的自证与对照

## 0. 直觉先行

把 v23 的证书体系想成一台手术：主刀、麻醉师、器械护士必须各司其职。若主刀顺手把麻醉记录也签了，即便手术成功，这套流程也已经不可信——因为「记录者」与「被记录者」是同一个人。

v23 里存在同样的味道。`FSVC.self_supervised_consistency` 用自监督伪标签去修改 CAC 覆盖图（`_update_cac_coverage_from_pseudo`），而 `adaptive_lambda` 与 `validate` 又拿这个覆盖率来判定 FSVC 自己是否有效。生产者、验证者、被验证对象三者合一，构成一个**自证闭环**。这正是「角色一致性」要处理的问题：不是问「证书内容对不对」，而是问「这张证书有没有资格由这个角色签发」。

第二个裂缝在对照。v23 实验表里有一列「基线 (v22)」，但 v22 的代码提交、容器、数据版本、随机种子、硬件指纹都没有被封存。「v23 比 v22 好」的参照物因此是口头的、可漂移的。「基线复现」要求的不是「再跑一遍看起来差不多」，而是：从密封工件出发、在**预注册**的容差内、由独立角色重放。容差必须在看到结果之前锁定，否则事后调大 ε 就能让任何结果「复现成功」。

## 1. 从直觉到两个可证伪的问题

### 1.1 角色一致性：谁在给谁作证？

v23 中有三处角色混同：

1. **FSVC 自证**：伪标签 → CAC 覆盖 → FSVC 的 λ 调度与 `validate`。覆盖率的「生产者」与「使用者」是同一模块。
2. **CFC+++ 信任自报标志**：`consensus_round` 直接读取票据里的 `few_shot_valid`、`ip_attested` 布尔值，却不校验这些标志由谁签发。一个被攻陷的机器人可以自报「我已通过 FSVC / IPAttest」。
3. **IPAM 的自审**：`verify_module` 对非核心模块直接返回 `True`，核心模块的「特征集合与权利要求一致」也标注为「简化：人工审核」。审核者与被审模块没有强制分离。

于是问题可写成：**给定计划 π 的证书集合 Cert(π)，是否存在一个静态可判定的角色划分 ρ，使得每张关键证书的签发者都属于与证据生产者不相交的角色？** 若存在，则自证、串谋与单点攻陷的代价被抬高。

### 1.2 基线复现：参照物能不能被重新造出来？

v23 的改进声明缺少三样东西：密封工件、确定性重放、预注册容差。缺了它们，「改进」不可证伪。问题可写成：**给定基线 B 的密封清单 M_B 与预注册容差 ε，能否在独立环境中重放出与提交指标在 ε 内一致的运行，并输出可机械复核的见证？** 若不能，任何相对 B 的改进声明都应被拒绝，而不是被解释为「环境差异」。

## 2. 核心新想法

### 2.1 角色类型化证书代数（Role-Typed Certificate Algebra）

给每张证书加两个字段：`evidence_module`（证据由谁生产）与 `issuer_id`（由谁签发）。角色集合取 `{PRODUCER, VERIFIER, AUDITOR, EXECUTOR}`，设计期对每个模块承诺一个角色划分 `ρ_0`，并把 `ρ_0` 的哈希写入版本五元组。关键证书满足：

- **非自证**：`issuer(c) ∉ producers(evidence(c))`；
- **职责分离**：同一关键证书链上 `PRODUCER`、`VERIFIER`、`AUDITOR` 两两不同主体；
- **角色稳定**：运行期 `ρ_t = ρ_0`，除非存在由两个不同角色共同签署的 `RoleChangeTicket`（双人控制）。

这把「谁有资格作证」从口头约定变成可机械检查的谓词，并直接封住 v23 的 FSVC 自证与 CFC+++ 信任自报标志两个漏洞。

### 2.2 角色漂移检测（Role Drift Monitor）

角色漂移指某模块在未走变更票据的情况下获得了新角色（例如 `fsvc` 悄悄获得 `AUDITOR` 权限，从而给自己的覆盖结论签字）。检测分两路：静态侧对代码中的 `@role:` 标记与注册表做哈希比对；运行侧对「证书签发者—证据生产者」的实际调用图做在线比对。漂移一旦发生，关键证书全部降级为 `CI`（不可判定），而不是静默通过。

### 2.3 密封基线 + 预注册容差 + 复现强度分级

基线复现证书 `BRC` 绑定一个五元组清单 `RManifest = (h_code, h_env, h_data, seed, h_hw)`，并要求：

- **预注册**：指标集合 `Metrics`、逐指标容差 `ε_m`、统计分析方法在运行 v24 之前提交到只追加的 `PreRegLedger`，得到 `commit_hash`；
- **重放**：从密封工件重建环境，重放基线，记录 `replay_metrics`；
- **判定**：`∀m ∈ Metrics: |replay_m − committed_m| ≤ ε_m`；
- **分级**：`R3` 位级一致、`R2` 跨环境且 ε 内、`R1` 同环境且 ε 内、`R0` 未复现。只有 `R1` 及以上才允许签发改进声明。

关键设计是**容差先于结果**。这把「复现」从一种事后叙事变成一种事前承诺，避免「结果不好就调 ε」的科研不端式退化。

### 2.4 把复现作为单调执行链的锚点

v23 的 `Exec_v23 ⊆ Exec_v22` 是集合层面的单调，但「v23 相对 v22 的改进」没有锚。v24 规定：任何跨轮改进声明必须同时引用一个 `R1+` 的基线复现证书，且该证书的 `issuer` 属于 `AUDITOR` 角色、独立于 v24 的生产者。于是改进声明本身也进入证书链，不能由提出改进的人自签。

## 3. 两个灵感词的互补性

- 「角色一致性」回答**谁可以作证**；
- 「基线复现」回答**参照物是什么、能否重建**。

单独做角色一致性，会得到一套「互相签字但参照物漂移」的官僚体系；单独做基线复现，会得到「数字可复现但由利益相关方自签」的可疑结论。两者叠加，才让「v24 相对 v23 有改进」成为一条可审计的陈述：独立角色 + 密封基线 + 预注册容差 + 机械复核见证。

## 4. 可证伪的预测

1. 在注入「FSVC 自报覆盖」攻击时，v24 的自证拦截率应为 100%，而 v23 为 0%（因为 v23 只检查数值，不检查签发者）。
2. 在 GPU 非确定性开启的跨环境重放中，v24 的 `R2` 复现率会显著低于同环境 `R1`；若二者接近，说明容差 ε 过松，复现退化为形式。
3. 角色划分越细，自证与串谋攻击成本越高，但合法跨角色交接导致的死锁率也越高；应存在一个可测的「角色粒度—死锁率」权衡曲线。

## 5. 本轮最大风险

**一句话**：角色划分与预注册容差都是「治理工件」——若同一主体既能修改 `ρ_0` 又能修改 `ε`，那么角色一致性与基线复现会同时坍缩为元层面的自证，系统看似多证齐全，实则仍由生产者给自己发合格证。

```python
# ============================================================
# IP-440 Role Consistency Certificate (RCC)
# ============================================================
class Role(Enum):
    PRODUCER = "PRODUCER"
    VERIFIER = "VERIFIER"
    AUDITOR  = "AUDITOR"
    EXECUTOR = "EXECUTOR"

@dataclass(frozen=True)
class CertificateEnvelope:
    cert_id: str
    evidence_module: str   # 证据由哪个模块生产
    issuer_id: str         # 由哪个主体签发
    role: Role
    payload_hash: bytes
    signature: bytes

@dataclass(frozen=True)
class RoleChangeTicket:
    module: str
    rho_old: frozenset
    rho_new: frozenset
    sig_auditor: bytes
    sig_verifier: bytes

    def valid(self, pk_a, pk_v) -> bool:
        if pk_a == pk_v:
            return False  # 双签必须来自不同主体
        return (verify_signature(pk_a, self._digest(), self.sig_auditor)
                and verify_signature(pk_v, self._digest(), self.sig_verifier))

    def _digest(self) -> bytes:
        return sha256(repr((self.module, sorted(self.rho_old), sorted(self.rho_new))).encode())

class RoleConsistencyCertificate:
    def __init__(self, rho0: dict[str, frozenset], partition_commit: bytes):
        self.rho0 = rho0
        self.partition_commit = partition_commit  # H(ρ₀)，随版本五元组下发
        self.rho_t = dict(rho0)
        self.issuer_of: dict[str, str] = {}       # module -> issuer_id
        self.tickets: list[RoleChangeTicket] = []

    def partition_digest(self) -> bytes:
        payload = sorted(
            (m, sorted(r.value for r in roles), self.issuer_of.get(m, ""))
            for m, roles in self.rho_t.items()
        )
        return sha256(json.dumps(payload, sort_keys=True).encode()).digest()

    def role_drift(self) -> bool:
        if self.partition_digest() == self.partition_commit:
            return False
        # 允许通过合法票据解释的变更
        return not all(t.valid(self.pk_a, self.pk_v) for t in self.tickets)

    def self_certifying(self, c: CertificateEnvelope) -> bool:
        # 证据生产者集合包含 evidence_module 的签发主体
        producer = self.issuer_of.get(c.evidence_module)
        return producer is not None and c.issuer_id == producer

    def check_cert(self, c: CertificateEnvelope, critical: bool) -> bool:
        if c.role not in self.rho_t.get(c.evidence_module, frozenset()):
            return False
        if not verify_signature(self.pk_of(c.issuer_id), c.payload_hash, c.signature):
            return False
        if critical:
            if self.self_certifying(c):
                return False
            # 关键证书必须由独立 V 或 A 签发，不能由 P 自签
            if c.role not in (Role.VERIFIER, Role.AUDITOR):
                return False
            # P/V/A 主体两两不同
            parties = {
                self.issuer_of.get(c.evidence_module),
                c.issuer_id,
                self.auditor_of.get(c.cert_id),
            }
            if len(parties) < 3:
                return False
        return True

    def check_plan(self, plan, certs: list[CertificateEnvelope]) -> bool:
        if self.role_drift():
            return False
        return all(self.check_cert(c, critical=(c.cert_id in plan.critical_certs))
                   for c in certs)


# ============================================================
# IP-441 Role Drift Monitor (RDM)
# ============================================================
class RoleDriftMonitor:
    def __init__(self, rcc: RoleConsistencyCertificate):
        self.rcc = rcc
        self.call_graph: dict[str, set[str]] = defaultdict(set)  # caller -> callees

    def observe(self, caller: str, callee: str):
        self.call_graph[caller].add(callee)

    def static_scan(self, root: Path) -> dict[str, list[str]]:
        """扫描 @role:ROLE 标记，与 ρ₀ 比对；缺失/越权即报告"""
        violations = defaultdict(list)
        for py in root.rglob("*.py"):
            mod = py.stem
            declared = set(re.findall(r"@role:(\w+)", py.read_text()))
            expected = {r.value for r in self.rcc.rho0.get(mod, frozenset())}
            if declared and not declared <= expected:
                violations[mod].append(f"undeclared_role:{declared - expected}")
        return violations

    def runtime_drift(self, cert: CertificateEnvelope) -> bool:
        """实际调用图显示证据模块被非授权角色调用/签发"""
        callers = {u for u, callees in self.call_graph.items()
                   if cert.evidence_module in callees}
        allowed = {u for u, rs in self.rcc.rho_t.items()
                   if Role.PRODUCER in rs}
        return not callers <= allowed


# ============================================================
# IP-442/443 Baseline Reproduction Certificate (BRC) + PreReg Ledger
# ============================================================
class ReproStrength(IntEnum):
    R0 = 0   # 未复现
    R1 = 1   # 同环境 ε 内
    R2 = 2   # 跨环境 ε 内
    R3 = 3   # 位级一致

@dataclass(frozen=True)
class RManifest:
    h_code: str
    h_env: str
    h_data: str
    seed: int
    h_hw: str

    def digest(self) -> bytes:
        return sha256(repr(self).encode()).digest()

@dataclass(frozen=True)
class PreRegistration:
    baseline_id: str
    metrics: tuple[str, ...]
    eps: dict[str, float]
    analysis: str
    commit_hash: bytes
    t_commit: float

class PreRegLedger:
    """只追加账本：预注册必须先于运行上链，事后不可改。"""
    def __init__(self):
        self.entries: list[PreRegistration] = []

    def commit(self, pre: PreRegistration) -> bytes:
        prev = self.entries[-1].commit_hash if self.entries else b"\x00" * 32
        h = sha256(prev + repr(pre).encode()).digest()
        self.entries.append(replace(pre, commit_hash=h))
        return h

    def anchored(self, commit_hash: bytes, t_run: float) -> bool:
        return any(e.commit_hash == commit_hash and e.t_commit < t_run
                   for e in self.entries)

class BaselineReproducer:
    def __init__(self, baseline_id: str, manifest: RManifest,
                 pre: PreRegistration, ledger: PreRegLedger):
        self.baseline_id = baseline_id
        self.manifest = manifest
        self.pre = pre
        self.ledger = ledger
        self.sealed: dict[str, bytes] = {}
        self.replay_metrics: dict[str, float] = {}

    def seal(self, artifacts: dict[str, bytes]) -> bytes:
        """封存基线工件，返回 Merkle 根"""
        for name, blob in artifacts.items():
            if sha256(blob).hexdigest() != self._expected(name):
                raise ValueError(f"artifact tampered: {name}")
            self.sealed[name] = blob
        return merkle_root(self.sealed.values())

    def replay(self, sandbox) -> dict[str, float]:
        t_run = time.now()
        if not self.ledger.anchored(self.pre.commit_hash, t_run):
            raise PermissionError("pre-registration missing or post-hoc")
        if self.manifest.h_env != sandbox.env_hash():
            raise PermissionError("environment mismatch")
        self.replay_metrics = sandbox.run(self.sealed, seed=self.manifest.seed)
        return self.replay_metrics

    def strength(self, committed: dict[str, float]) -> ReproStrength:
        diffs = {m: abs(self.replay_metrics[m] - committed[m]) for m in self.pre.metrics}
        if all(d == 0 for d in diffs.values()):
            return ReproStrength.R3
        if all(d <= self.pre.eps[m] for m, d in diffs.items()):
            return (ReproStrength.R2
                    if self.manifest.h_env != committed.get("_env")
                    else ReproStrength.R1)
        return ReproStrength.R0

    def certify(self, committed: dict[str, float], issuer_id: str,
                pk_auditor) -> Optional['BaselineReproductionCertificate']:
        s = self.strength(committed)
        if s < ReproStrength.R1:
            return None
        witness = sha256(repr((self.manifest.digest(), self.pre.commit_hash,
                               sorted(self.replay_metrics.items()))).encode()).digest()
        return BaselineReproductionCertificate(
            baseline_id=self.baseline_id, strength=s, witness=witness,
            issuer_id=issuer_id,
            sig=sign(pk_auditor, witness),
        )

@dataclass(frozen=True)
class BaselineReproductionCertificate:
    baseline_id: str
    strength: ReproStrength
    witness: bytes
    issuer_id: str
    sig: bytes

    def improvement_valid(self, delta: dict[str, float], eps: dict[str, float],
                          ci: dict[str, tuple[float, float]]) -> bool:
        if self.strength < ReproStrength.R1:
            return False
        return all(delta[m] > 2 * eps[m] and (ci[m][0] > 0 or ci[m][1] < 0)
                   for m in delta)

class HPCEPlusPlus:

               modules: list[str], certs: list[CertificateEnvelope],
               delta: dict[str, float], eps: dict[str, float],
               ci: dict[str, tuple[float, float]]) -> bool:
        # 1. v23 四证门

        if self.rcc.role_drift() or not self.rcc.check_plan(plan, certs):
            return False
        if any(self.rdm.runtime_drift(c) for c in certs if c.cert_id in plan.critical_certs):
            return False
        # 3. 基线复现（改进声明必须锚定 R1+ 且审计者独立于 v24 生产者）
        if self.brc.strength < ReproStrength.R1:
            return False
        if self.brc.issuer_id in {c.issuer_id for c in certs
                                  if c.role == Role.PRODUCER}:
            return False
        if not self.brc.improvement_valid(delta, eps, ci):
            return False
        return True
```

## 2. 复杂度分析

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 |
|---|---|---|---|
| RCC 分区哈希 | O(\|M\| log\|M\|) | O(\|M\|) | \|M\|≤20 模块 |
| RCC 单证书检查 | O(1) 验签 + O(1) 角色查表 | O(1) | 关键证书数≤50 |
| RDM 静态扫描 | O(\|codebase\|) 离线 | O(\|M\|) | CI 阶段执行 |
| RDM 运行期漂移 | O(deg(call_graph)) | O(\|E_call\|) | 在线增量 |
| PRL 提交/锚定 | O(1) 追加 / O(log\|ledger\|) 索引 | O(\|ledger\|) | 每轮一次 |
| BRC 重放 | O(基线训练/推理成本) 离线 | O(\|artifacts\|) | 离线，不占控制环 |
| HPCE++ 准入 | O(\|modules\| + \|certs\|) | O(1) 增量 | 在线 <20ms |
| 端到端单步 | 同 v23 + O(\|certs\|) | 同 v23 | 50Hz 实时约束保持 |

**实时性**：RCC 与 RDM 在线检查均为 O(\|certs\|) 查表/验签；BRC 重放完全离线，不进入控制环，因此 v24 的在线延迟相对 v23 只增加常数级验签开销。

## 3. 正确性论证

### 引理 5（角色分离抬高自证与串谋成本）
**陈述**：若 `RoleConsistent(π)` 成立，则对每张关键证书 c，`issuer(c) ∉ producers(c)`，且伪造一张被接受的关键证书至少需要同时攻陷生产、验证、审计三个不同主体中的两个。

**证明**：
1. `check_cert` 对关键证书要求 `role(c) ∈ {V, A}` 且 `¬self_certifying(c)`，因此签发者不可能同时是证据生产者。
2. 证书签名绑定 `payload_hash`；篡改证据需重签，而重签需 `pk_of(issuer)` 对应的私钥。
3. `parties` 要求生产、签发、审计三个主体两两不同，任一单点攻陷至多控制一个主体，无法同时满足三方条件。
4. 角色漂移若发生且无合法双签票据，`role_drift()` 直接拒绝整份计划，而不是逐证书降级，避免「局部放行」。
∎

### 引理 6（预注册容差使改进声明可证伪）
**陈述**：若 `BRC(B).strength ≥ R1` 且 `ε` 在运行前已上链，则对任意指标 m，当 `Δ_m > 2ε_m` 且置信区间与 0 不相交时，改进不能由基线复现噪声解释。

**证明**：
1. 复现要求 `|replay_m − committed_m| ≤ ε_m`，即基线提交值相对真实重放的不确定半径为 `ε_m`。
2. 改进量 `Δ_m = metric_v24 − committed_m`，最坏情况下真实改进为 `Δ_m − ε_m`；要求 `Δ_m > 2ε_m` 保证即使 v24 也带有同量级 `ε_m` 噪声，下界仍 `> ε_m > 0`。
3. CI 与 0 不相交进一步排除统计波动；两者同时满足时，改进不可由复现误差解释。
4. 若 `ε` 事后修改，`ledger.anchored` 因哈希链断裂而返回 false，BRC 无法签发。
∎

### 引理 7（角色—基线耦合防止「移动基线」）
**陈述**：`ImprovementValid(Δ; BRC)` 要求 BRC 由独立于 v24 生产者的审计者签发，因此「把基线调低以制造改进」至少需要生产与审计两个主体串谋，且会被角色划分检查记录。

**证明**：
1. BRC 的 `issuer_id` 必须属于 `AUDITOR`，且 `HPCEPlusPlus.admits` 检查其不在 v24 生产者集合中。
2. 基线工件由 `RManifest` 五元组哈希封存，替换基线会改变 `h_code/h_data` 并使 `verify_seal` 失败。
3. 角色划分哈希 `H(ρ₀)` 随版本五元组下发，改变审计者身份需 `RoleChangeTicket` 双签，留下可审计记录。
∎

### 引理 8（五证单调退化链）
**陈述**：`Exec_v24 ⊆ Exec_v23 ⊆ Exec_v22 ⊆ …` 恒成立。

**证明**：
- `Exec_v24 = Exec_v23 ∩ Fil_role ∩ Fil_repro`，由交集定义直接得 `Exec_v24 ⊆ Exec_v23`。
- 任一新增过滤器失效（角色漂移、复现失败、改进不显著）时，对应计划被拒，执行集只会收缩，不会新增。
- 回退到 v23 行为时 `Fil_role = Fil_repro = ⊤`，`Exec_v24 = Exec_v23`，链保持连续。
∎

### 定理（HPC-E++ 五证准入门的安全—合规—可部署—可保护—可复现完备性）
**陈述**：对任意计划 π，`HPCEPlusPlus.admits(π) = True` ⟺ π 同时满足：
(1) 物理接地安全（几何∧规范∧负信息∧能量∧差距）；
(2) 云边版本一致性与统计覆盖承诺；
(3) 少样本适应后 conformal 覆盖 ≥1-α；
(4) 核心模块专利保护完备且无侵权风险；
(5) 角色分离且基线复现 R1+、改进声明可证伪。

**证明**：由 `HPCEPlusPlus.admits` 的五个连言条件，分别对应引理 1–4（v23）与引理 5–8（v24）。必要性：任一条件缺失即拒证。充分性：五条件全满足时，v23 的安全/合规/保护链与 v24 的角色/复现链同时成立，且由引理 8 保证执行集单调。∎

## 4. 已知风险与缓解

| 风险编号 | 描述 | 严重度 | 缓解措施 | 剩余风险 |
|---|---|---|---|---|
| R6 | 角色划分过细导致合法跨角色交接死锁（例如边端只有单一进程，无法真正分离 P/V/A） | 高 | 1) 逻辑角色与物理进程解耦，允许同一进程以不同密钥/身份承担多角色；2) 死锁检测后触发降级票据；3) 角色粒度—死锁率曲线离线标定 | 资源受限边端难以提供真正独立的审计主体，可能退化为「同机不同密钥」的弱分离 |
| R7 | 跨环境基线复现受 GPU 非确定性、浮点归约顺序、线程调度影响，R2/R3 难以达到 | 高 | 1) 固定 seed + 确定性算子 + 单线程归约；2) 允许 R1 同环境复现作为最低门槛；3) 记录 h_hw，将硬件差异显式纳入 ε | 若 ε 为迁就硬件而放宽，改进声明可能被噪声吞没，复现退化为形式 |
| R8 | 预注册容差 ε 与指标集合在事后被治理层修改 | 最高 | 1) PRL 只追加 + 哈希链；2) 修改需新开一轮并显式记录「事后变更」；3) CI 中校验 commit 时间戳早于运行 | 若账本实现方与实验方为同一主体，时间戳可信度依赖外部锚定 |
| R9 | 角色一致性检查增加验签开销，影响 50Hz 控制环 | 中 | 1) 关键证书验签结果缓存；2) 每控制周期只验增量证书；3) 离线预验签 + 在线哈希比对 | 缓存失效窗口内可能出现短暂旧角色放行 |

## 6. 本轮最大风险（最终确认）

**一句话**：角色划分 `ρ₀` 与预注册容差 `ε` 都是「治理工件」——若同一主体既能修改角色划分又能修改容差，那么角色一致性与基线复现会同时坍缩为元层面的自证，系统看似五证齐全，实则仍由生产者给自己发合格证。
