# 第 1 轮（新灵感循环第 1 轮；本轮灵感：「多机器人协作」×「成功率」）

> **基线**：上一循环产出 MetricVoiceGauge-NCD-HUTDH-v20 + IP-420–424（感知层：PCA/CTS/CFC/HPC/CFCtrl）。v20 及更早的 v19（DCM/OGCC/CCV/DRS/OGC）、v17（CLP/S2C/HCG/PSV/APS/AMC）全部保留。
> 本轮纪律：**协作是承诺的互锁，成功率是可证书化的下界；安全不等于成功，成功率也不是可乘的概率**。本轮只做一件事：在 v20 的碰撞安全证书之上，增加一层**可审计的协作成功率证书**，使多机器人系统能在“零碰撞”之外，对“任务能否完成”给出对机器人间相关性分布无关的下界。

## 0. 直觉与动机

### 灵感 1（多机器人协作 → 协作是承诺互锁，不是并行执行）

**直觉。** 多机器人系统最常见的失败不是撞上，而是“等”：A 等 B 释放通道，B 等 C 交付物体，C 等 A 让出工位；v20 的碰撞证书对此完全沉默，因为它只检查几何，不检查承诺。另一种失败是“承诺被打破”：某机器人声称“2 秒内离开通道”，实际 3 秒才离开，其他机器人按旧承诺进入，于是要么碰撞，要么急停。可见，碰撞安全是成功的**必要条件**，不是充分条件；成功还要求**承诺在时间、资源和进度上互锁**。

**严谨定义。** 每个机器人 n 不提交一条不可变的轨迹，而提交一个**可撤销承诺**
κ_n = (n, r_n, W_n, P_n, σ_n^abort, cert_n)，
其中 r_n 是独占资源（通道、工位、工具、人体安全区），W_n = [a_n, b_n] 是占用窗口，P_n = [p_n^-, p_n^+] 是**认证进度区间**，σ_n^abort 是已由 v20 认证的退路，cert_n 是 v20 证书 id。联合计划 π 被 **协作承诺证书 (Cooperative Commitment Certificate, CCC)** 接受，当且仅当：

1. **资源兼容**：若 r_n = r_m，则 W_n 与 W_m 之间至少相隔 δ_sep，或按资源分配图形成确定的先后序；
2. **无死锁**：以机器人和资源为节点的资源分配图无环；
3. **可撤销**：每个 σ_n^abort ∈ Exec_v20，且在 Δ_abort 内释放 r_n；
4. **进度一致**：若 n 必须向 m 交付，则 b_n ≤ a_m 且 p_n^- ≥ req_{n→m}。

关键反直觉点：**协作的可靠性不来自更强的联合规划器，而来自“可撤销的局部承诺”**——承诺越容易在违约前被撤销，联合成功率的下界反而越高，因为失败被局部化，不会沿等待链传播。

### 灵感 2（成功率 → 成功率是证书下界，不是预测标量）

**直觉。** 论文里的“成功率 92%”通常是一次实验的点估计；换一批初始状态、换一种光照，它就不再成立。更糟的是，多机器人成功率常被写成各机器人成功率的乘积，隐含独立假设；一旦存在共同失效（同一反光、同一网络分区、同一标定偏差），乘积会系统性高估。我们需要的是：**在声明的任务分布与可观测环境层上，对任意机器人间相关性都成立的下界**。

**严谨定义。** 固定任务 T = (G, H, X_0, μ)，G 是目标集，H 是截止时间，X_0 是联合初始状态集，μ 是预注册的参考测度。把任务成功定义为
S = C ∩ ⋂_{n=1}^N S_n，
其中 C 是承诺兼容事件（CCC 通过时 C 为真），S_n 是“机器人 n 在承诺输入被履行的条件下，于 H 内到达其子目标且不违反 v20 证书”的事件。对每个环境层 e，计算**局部认证下界**
ℓ_n(e) = μ({x_0 ∈ X_0(e) : x_0 被 SLC 认证为属于 S_n}) / μ(X_0(e))。
联合下界**不乘**，而用 **Fréchet 下界**
L(e) = 1_C · max(0, Σ_{n=1}^N ℓ_n(e) − (N−1))，
并取最坏层 L = min_e L(e)。关键反直觉点：**不要乘成功率；乘法假设独立，Fréchet 下界对任意相关性都成立**——它由最弱环节主导，越保守越可信。

### 灵感 3（二者统一 → 共同失效分层与最弱分层分配）

**直觉。** 多机器人协作的成功率不是被“平均能力”限制，而是被**最坏环境层**和**最弱机器人**限制。若把光照、遮挡、负载、网络分区作为**运行前可观测的环境分层** e，在每个层内分别认证 ℓ_n(e)，再取 L = min_e L(e)，就能把 v20 最担心的“相关感知误差”变成“层内不依赖相关性、层间取最坏”的可审计结构。进一步，角色分配不应最大化期望成功率，而应最大化**最弱分层的认证下界**。

**严谨定义。** 令 E 是预注册的、由运行前可观测协变量定义的环境分层（不得用结果标签定义，否则泄漏）。**共同失效分层器 (Common-Mode Stratifier, CMS)** 负责把当前观测分类到 e ∈ E；若观测落在所有层的 OOD 阈值之外，返回 UNKNOWN，并令 L = 0。**认证角色分配 (Certified Role Allocation, CRA)** 求解
α* = argmax_α min_{e∈E} L(e; α)
s.t. 每个子任务被覆盖；∀n,e: ℓ_n(e; α) ≥ ℓ_n^min(e)；CCC(α) = OK。
只接受 Φ(α*) ≥ Φ(α_prev) 且无局部退化的分配，其中 Φ(α) = min_e L(e; α)。关键反直觉点：**提高协作成功率不是让每个机器人更强，而是让最弱环节的认证下界最高**；CRA 的目标是 max-min，而不是 max-mean。

### 三者如何统一

统一为 v20 之上的**协作成功率证书层 (Cooperative Success Certification Layer, CSCL)**：v20 回答“给定几何与感知，联合计划是否零碰撞”；v21 回答“给定承诺、环境层与任务分布，联合计划的任务成功率下界是多少”。CCC 是承诺侧（兼容、无死锁、可撤销），SLC 是度量侧（局部下界、Fréchet 联合下界），CMS 是环境侧（分层、共同失效、层间取最坏），CRA 是分配侧（max-min 角色分配），SRFC 是运行时侧（进度监控、承诺撤销、回退 v20）。共享状态 ζ_succ = (commitments, strata, local_bounds, joint_bound, allocation, fallback_state, mode_succ)。统一接口：**CCC+SLC+CMS+CRA 全通过时，计划进入 Exec_v21 并附带成功率下界证书；任一失败则回退 v20：仍然零碰撞，但 v21 不声称任何成功率下界。**

## 1. 研究问题（轮次升级版）

- **Q1（承诺互锁的可靠性）**：如何定义承诺的资源窗口、进度区间与退路，使 CCC 的接受条件既充分排除死锁与资源冲突，又不至于把可行计划全部拒绝？当多个机器人持有多个资源时，资源分配图的无环性如何在线维护？承诺撤销后如何增量重认证，而不是全量重规划？
- **Q2（局部成功率下界的保守性）**：如何用 v20 的 CCV/HPC 与区间进度，计算对任意扰动都成立的局部下界 ℓ_n(e)？当进度区间过宽导致 ℓ_n 很小时，如何在不引入分布假设的前提下收紧（例如证书引导的动作选择、分层细化）？Fréchet 下界在 N 较大时趋于 0，何时可以用**已认证的相关性包络**安全收紧？
- **Q3（共同失效分层的可操作性）**：如何选择运行前可观测、且与失效机制因果相关的分层协变量，使层内相关性不破坏边际下界？如何检测部署中出现未枚举的层（OOD），并在一个控制周期内冻结为 v20？分层过细会导致样本不足，过粗会掩盖共同失效，如何定标？
- **Q4（最弱分层分配与运行时撤销）**：如何在 N ≤ 10、子任务数 M 可能较大的情况下，快速求解 max-min 认证分配？当实际进度低于认证下界、窗口即将到期或层发生漂移时，SRFC 如何在不引发振荡的前提下触发承诺撤销、释放资源并回退 v20？如何保证 `Exec_v21 ⊆ Exec_v20`？

## 2. 设计原则（在 P31–P33 基础上新增 P34–P36）

**P34 承诺互锁律（Commitment Interlocking）**
联合计划 π 进入 `Exec_v21` 的必要条件是 CCC(π) = OK：资源兼容、资源分配图无环、每个机器人有已认证退路、进度区间满足依赖。**承诺是可撤销的**：若运行时进度低于认证下界、窗口即将到期或层漂移，机器人必须在违约前执行 σ_n^abort 并释放资源。**任何承诺撤销都只能让联合计划回到 v20 的安全域，不能扩张动作集**。因此 `Exec_v21 ⊆ Exec_v20`。

**P35 成功率下界律（Success Lower-Bound）**
在预注册的任务测度 μ 与环境分层 E 上，对每个 e ∈ E 计算局部下界 ℓ_n(e)，联合下界为
`L(e) = 1_C · max(0, Σ_n ℓ_n(e) − (N−1))`，`L = min_{e∈E} L(e)`。
**禁止把成功率相乘**；乘法等价于假设机器人间独立，Fréchet 下界不依赖该假设。若 μ 未声明、E 未覆盖当前观测、或任一局部证书失效，则 `L = 0`，v21 不声称成功率。**下界只能随认证信息增加而单调不减；不得用未认证的经验数据抬高 L。**

**P36 最弱分层分配律（Worst-Stratum Allocation）**
角色分配 α 的认证势函数为 `Φ(α) = min_{e∈E} L(e; α)`。只接受满足以下条件的 α：

1. 覆盖所有子任务；
2. 对每个机器人与每个层，局部下界不下降：`ℓ_n(e; α) ≥ ℓ_n(e; α_prev)`；
3. CCC(α) = OK；
4. `Φ(α) ≥ Φ(α_prev)`。

**分配的目标是 max-min，不是 max-mean**；不允许通过把难任务推给某个机器人来抬高平均值。**分配只改变承诺结构，不改变 v20 的碰撞证书；任何分配都必须落在 `Exec_v20` 内。**

## 3. 与基线的接口（如何退化）

- CCC 失效（承诺不可兼容/资源分配图有环）⇒ 不生成联合承诺，只执行单机器人 v20 计划，`L = 0`（不声称成功率），安全等价 v20；
- SLC 失效（进度区间不可认证/任务测度未声明）⇒ `L = 0`，回退 v20 执行；
- CMS 失效（当前观测 OOD/层支持不足）⇒ 该层 `L = 0`，SRFC 在一个控制周期内冻结为 v20；
- CRA 失效（分配搜索超时/无可行改进）⇒ 保持上一分配，不降低任何局部下界，安全等价 v20；
- SRFC 失效（监控超时/退路不可用）⇒ 直接回退 v20 的 APS 默认路径；
- 全部失效 ⇒ 完全回退 v20：零碰撞，但无成功率声明；
- **安全继承**：v21 只增加承诺、进度与分层约束，不删除 v20 的任何证书检查，故 `Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19`。

## 4. 预期贡献

1. **承诺互锁证书**：首次把多机器人协作的成功条件从“联合轨迹可行”改写为“可撤销承诺的互锁”，给出资源兼容、无死锁与认证退路的可检查条件；
2. **相关性无关的成功率下界**：给出基于区间进度与 Fréchet 不等式的成功率下界证书，明确区分“对相关性分布无关”与“对任务分布无关”，避免乘积式成功率的系统性高估；
3. **共同失效分层**：把 v20 的“相关感知误差”风险转化为可观测环境层上的逐层认证与最坏层取界，并给出 OOD 冻结机制；
4. **max-min 认证角色分配**：给出带非退化约束的分配算法，使成功率下界的提升不牺牲任何机器人或任何环境层；
5. **运行时承诺撤销**：给出 SRFC 的进度监控、窗口预警、层漂移冻结与 v20 回退，使“承诺违约”不再变成碰撞或急停，而是可审计的局部失败。

## 5. 本轮最大风险

**一句话**：v21 的成功率下界严格依赖**预注册的环境分层 E 与任务测度 μ**；一旦部署中出现未枚举的共同失效层（例如新型反光、遮挡、网络分区组合），层内边际下界 ℓ_n(e) 会失效，而 Fréchet 公式仍会给出一个看似合理的 L——系统将以“已认证成功率”的名义系统性高估真实成功率。

## 1. 关键算法骨架

**定义 821（认证进度区间）** 给定层 e、机器人 n、控制步 k、状态 x 与动作 a。若 v20 的 CCV/HPC 对 (n, x, a, e) 返回 SAFE，则定义单步认证进度下界
`g_lo(n, a, x, e) = min_{x' ∈ Cell(x), d ∈ D_e} [φ(f(x, a, d)) − φ(x)]`，
其中 Cell(x) 是 x 所在的 v20 证书单元，D_e 是层 e 内声明的不确定性集合，f 是名义动力学。若 CCV/HPC 返回 UNKNOWN 或 UNSAFE，则 `g_lo = −∞`，该步不计入成功。若沿证书单元传播有 `Σ_k g_lo,k ≥ φ(x_0) − φ(G)`，则 x_0 被认证为成功。**该定义只使用最坏情况区间，不假设任何概率分布。**

```python
# ---------------- IP-425 Cooperative Commitment Certificate ----------------
@dataclass(frozen=True)
class Commitment:
    robot: int
    resource: Hashable
    window: Tuple[float, float]          # [a_n, b_n]
    progress: Tuple[float, float]        # [p_n^-, p_n^+]
    abort_path: "AbortPath"
    cert_id: str
    stratum: str
    delivers: Tuple[Tuple[int, float], ...] = ()  # (下游机器人, 所需进度)


class CooperativeCommitmentCertificate:
    def __init__(self, v20, delta_sep=0.05, delta_abort=0.2):
        self.v20 = v20
        self.delta_sep = delta_sep
        self.delta_abort = delta_abort

    def certify(self, commitments, horizon):
        # (1) 同一资源的占用窗口必须分离
        by_res = defaultdict(list)
        for c in commitments:
            by_res[c.resource].append(c)
        for res, cs in by_res.items():
            cs = sorted(cs, key=lambda c: c.window[0])
            for a, b in zip(cs, cs[1:]):
                if a.window[1] + self.delta_sep > b.window[0]:
                    return False, f"RESOURCE_OVERLAP:{res}"

        # (2) 资源分配图无环：排除循环等待
        if self._has_cycle(self._resource_graph(commitments)):
            return False, "DEADLOCK_RISK"

        # (3) 每个承诺都有已认证退路，且退路能在时限内释放资源
        for c in commitments:
            if not self.v20.certifies(c.abort_path):
                return False, f"NO_CERTIFIED_ABORT:{c.robot}"
            if c.window[0] + self.delta_abort > horizon:
                return False, f"ABORT_DEADLINE:{c.robot}"
            if not c.abort_path.releases(c.resource):
                return False, f"ABORT_DOES_NOT_RELEASE:{c.robot}"

        # (4) 依赖上的进度区间一致
        if not self._progress_consistent(commitments):
            return False, "PROGRESS_INCONSISTENT"
        return True, "OK"

    def _resource_graph(self, commitments):
        # 节点：("r", robot) 与 ("R", resource)；边：申请、分配、等待
        edges = defaultdict(set)
        for c in commitments:
            edges[("r", c.robot)].add(("R", c.resource))
        for c in commitments:
            for m, _ in c.delivers:
                edges[("R", c.resource)].add(("r", m))
        return edges

    def _has_cycle(self, edges):
        color = defaultdict(int)
        def dfs(u):
            color[u] = 1
            for v in edges[u]:
                if color[v] == 1:
                    return True
                if color[v] == 0 and dfs(v):
                    return True
            color[u] = 2
            return False
        return any(color[u] == 0 and dfs(u) for u in list(edges))

    def _progress_consistent(self, commitments):
        by_id = {c.robot: c for c in commitments}
        for c in commitments:
            for m, req in c.delivers:
                d = by_id.get(m)
                if d is None:
                    return False
                if c.window[1] > d.window[0] or c.progress[0] < req:
                    return False
        return True


# ---------------- IP-426 Success-Rate Lower-Bound Certificate ----------------
class SuccessRateLowerBoundCertificate:
    def __init__(self, v20, task, dt=0.02):
        self.v20 = v20
        self.task = task            # (G, H, X_0, μ, potential)
        self.dt = dt

    def local_bound(self, robot, stratum, joint_initial_set):
        certified = 0
        for x0 in joint_initial_set:
            if self._certified_reaches(robot, stratum, x0):
                certified += 1
        return certified / max(1, len(joint_initial_set))

    def _certified_reaches(self, robot, stratum, x0):
        # x 以证书单元 Cell(x) 传播；代码用名义状态表示
        K = int(self.task.horizon / self.dt)
        progress_lo = 0.0
        x = x0
        for k in range(K):
            a = robot.policy(x, k, stratum)
            if not self.v20.certifies_step(robot, a, x, stratum):
                return False
            g_lo = self.v20.progress_lower_bound(
                robot, a, x, stratum, self.task.potential)
            if g_lo == float("-inf"):
                return False
            progress_lo += g_lo
            x = robot.step(x, a)
            if progress_lo >= self.task.required_progress(x0):
                return True
        return False

    def joint_bound(self, local_bounds, compatible):
        if not compatible:
            return 0.0
        N = len(local_bounds)
        # Fréchet 下界：对任意相关性成立，不假设独立
        return max(0.0, sum(local_bounds) - (N - 1))

    def worst_stratum_bound(self, per_stratum):
        return min(per_stratum.values()) if per_stratum else 0.0


# ---------------- IP-427 Common-Mode Stratifier ----------------
class CommonModeStratifier:
    def __init__(self, covariates, min_support=0.05, ood_threshold=3.0):
        self.covariates = covariates     # 运行前可观测：光照、遮挡率、负载、网络状态等
        self.min_support = min_support
        self.ood_threshold = ood_threshold
        self.strata = {}                 # sid -> (mean, cov, support)

    def fit(self, calibration_log):
        X = [self._features(r) for r in calibration_log]
        labels = self._cluster(X)
        for lab in sorted(set(labels)):
            idx = [i for i, l in enumerate(labels) if l == lab]
            if len(idx) / len(X) < self.min_support:
                continue
            self.strata[lab] = (mean([X[i] for i in idx]),
                                cov([X[i] for i in idx]),
                                len(idx) / len(X))
        return self.strata

    def classify(self, observation):
        x = self._features(observation)
        best, best_d = None, float("inf")
        for sid, (mu, sigma, _) in self.strata.items():
            d = mahalanobis(x, mu, sigma)
            if d < best_d:
                best, best_d = sid, d
        if best_d > self.ood_threshold:
            return None                  # UNKNOWN_STRATUM -> L = 0
        return best

    def _features(self, r):
        return [r[c] for c in self.covariates]

    def _cluster(self, X):
        # 只用运行前可观测协变量聚类；不得使用碰撞/成功标签
        k = min(8, max(2, len(X) // 50))
        return kmeans(X, k=k)


# ---------------- IP-428 Certified Role Allocator ----------------
class CertifiedRoleAllocator:
    def __init__(self, ccc, slc, cms, L_min=0.6):
        self.ccc = ccc
        self.slc = slc
        self.cms = cms
        self.L_min = L_min

    def allocate(self, subtasks, robots, strata, baseline):
        best = None
        for alpha in self._assignments(subtasks, robots):
            if not self._covers(alpha, subtasks):
                continue
            commitments = self._build_commitments(alpha)
            ok, _ = self.ccc.certify(commitments, self.slc.task.horizon)
            if not ok:
                continue
            bounds = self._certified_stratum_bounds(alpha, strata, baseline)
            if bounds is None:
                continue
            phi = min(bounds.values())
            if phi < self.L_min:
                continue
            if best is None or phi > best.phi:
                best = Allocation(alpha, bounds, phi)
        return best

    def _certified_stratum_bounds(self, alpha, strata, baseline):
        bounds = {}
        for e in strata:
            lbs = []
            for s in alpha.subtasks:
                r = alpha[s]
                lb = self.slc.local_bound(r, e, self.slc.task.initial_set[e])
                if lb < baseline[r][e]:
                    return None          # 非退化约束失败
                lbs.append(lb)
            bounds[e] = self.slc.joint_bound(lbs, compatible=True)
        return bounds

    def _assignments(self, subtasks, robots):
        # N ≤ 10：分支定界；上界用逐层 Fréchet 的局部上界，剪掉不可能改进的分支
        yield from branch_and_bound(subtasks, robots, upper_bound=self._upper_bound)


# ---------------- IP-429 Success-Rate Fallback Controller ----------------
class SuccessRateFallbackController:
    def __init__(self, aps, cfctrl, cms, slc, L_min=0.6,
                 delta_abort=0.2, progress_margin=0.02):
        self.aps = aps
        self.cfctrl = cfctrl
        self.cms = cms
        self.slc = slc
        self.L_min = L_min
        self.delta_abort = delta_abort
        self.progress_margin = progress_margin

    def tick(self, plan, commitments, t, progress, observation):
        # (1) 当前观测必须属于预注册层；否则冻结为 v20
        e = self.cms.classify(observation)
        if e is None:
            return self._freeze_to_v20(plan, "STRATUM_SHIFT")

        # (2) 进度必须在认证下界之上；窗口必须在到期前释放
        for c in commitments:
            if progress[c.robot] < c.progress[0] + self.progress_margin:
                return self._renounce(plan, c, "PROGRESS_SHORTFALL")
            if t >= c.window[1] - self.delta_abort and not plan.resource_released(c.resource):
                return self._renounce(plan, c, "WINDOW_EXPIRING")

        # (3) 复用 v20 的联邦共识新鲜度；过期则回退
        if self.cfctrl.check_fed_freshness(plan.hpc, t) == "V19_CONSENSUS_EXPIRED":
            return self._freeze_to_v20(plan, "CONSENSUS_EXPIRED")
        return "OK"

    def _renounce(self, plan, c, reason):
        plan.execute_abort(c.abort_path)
        plan.release(c.resource)
        L = self._recompute_bound(plan)
        if L < self.L_min:
            return self._freeze_to_v20(plan, "SUCCESS_BOUND_TOO_LOW")
        return self.aps.activate_freshness_ladder(plan, force_mode="V20_REPLAN")

    def _freeze_to_v20(self, plan, reason):
        plan.mode_succ = "V20_FREEZE"
        return self.aps.activate_freshness_ladder(plan, force_mode="V20")
```

## 3. 推导

**引理 157（承诺互锁的碰撞安全性）** 若 CCC(κ)=OK，则任何履行全部承诺的联合执行在共享资源上无冲突、无死锁；结合 v20 的局部证书，联合执行在机器人-物体与机器人-机器人上均零碰撞。
证明：资源兼容条件排除同一资源的窗口重叠；资源分配图无环排除循环等待；每个机器人持有资源期间的行为受 v20 证书约束；退路已认证且能释放资源。故共享资源冲突与死锁均不可能，局部碰撞由 v20 排除。∎

**引理 158（局部成功率下界的可靠性）** 对层 e 与机器人 n，若 ℓ_n(e) 由定义 821 的认证进度区间计算，则对 μ-几乎所有的 x_0 ∈ X_0(e)，只要 x_0 被计入认证集，S_n(e) 成立；因此 P(S_n(e)) ≥ ℓ_n(e)。
证明：认证集是 S_n(e) 的子集；由测度单调性即得。∎

**引理 159（Fréchet 联合下界）** 对任意联合分布与任意事件 S_1,...,S_N，若 P(S_n(e)) ≥ ℓ_n(e)，则
`P(⋂_n S_n(e)) ≥ max(0, Σ_n ℓ_n(e) − (N−1))`。
证明：由并集界，
`P(⋃_n S_n^c(e)) ≤ Σ_n P(S_n^c(e)) ≤ Σ_n (1−ℓ_n(e)) = N − Σ_n ℓ_n(e)`；
取补即得；下界与 0 取最大。该界不依赖 S_n 之间的相关性。∎

**引理 160（分层共同失效的鲁棒性）** 若 CCC 通过（C=1），且对每个 e∈E，L(e) 由引理 159 给出，则对任意支撑在 E 上的环境分布，`P(S) ≥ L = min_e L(e)`。若当前观测不在 E 内，则 L=0，v21 不声称成功率。
证明：`P(S) = Σ_e P(e)P(S|e) ≥ Σ_e P(e)L(e) ≥ min_e L(e)`。∎
注意：该界不消除共同失效，而是要求共同失效机制被某个可观测层 e 捕获；未捕获的层是最大风险。

**引理 161（分配的非退化与安全继承）** CRA 只接受满足 `ℓ_n(e;α) ≥ ℓ_n(e;α_prev)` 且 `Φ(α) ≥ Φ(α_prev)` 的 α；故局部下界与最坏层下界均不下降。又每个 α 的承诺均通过 CCC，且每个执行仍在 Exec_v20 内，故 `Exec_v21 ⊆ Exec_v20`。∎

**引理 162（承诺撤销的局部失败性）** 若 SRFC 在 `progress < p_n^- + δ_prog` 或窗口到期前 Δ_abort 触发撤销，则机器人执行已认证退路并释放资源；因此撤销只会把联合执行带回 v20 安全域，不会产生新的碰撞，也不会把失败传播给下游承诺。∎

**引理 163（v21 整体安全与成功率下界）** 在预注册的 T=(G,H,X_0,μ) 与 E 下，若 CCC+SLC+CMS+CRA 全部通过，则
(1) `Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19`；
(2) 对任意支撑在 E 上的环境分布与任意机器人间相关性，`P(S) ≥ L`。
证明：由引理 157–162 组合。∎

## 7. 已知风险与失效模式

1. **未枚举的共同失效层**：v21 的下界条件在预注册层 E 上成立；若部署中出现新型反光、遮挡、网络分区组合，且 CMS 未将其判为 OOD，则 ℓ_n(e) 的边际下界失效，Fréchet 仍会输出一个看似合理的 L。缓解：扩大可观测协变量、在线 OOD 检测、未知层强制 L=0 并冻结 v20。
2. **Fréchet 下界的松弛性**：N 较大时 `Σℓ_n − (N−1)` 可能为 0，即使每个机器人单独成功率很高。缓解：只在能认证正相关/共单调时使用更紧的依赖包络；或将任务分解为失效机制相对独立的小组，但不得无条件假设独立。
3. **承诺模型与执行延迟不匹配**：实际执行可能超出 W_n，SRFC 会触发撤销，但频繁撤销会降低成功率。缓解：鲁棒的窗口标定、延迟裕量、增量重规划。
4. **局部进度区间过宽**：区间传播可能使 ℓ_n 很小，导致成功率下界无信息量。缓解：证书引导的动作选择、细化 Cell、使用更紧的势函数。
5. **分配组合爆炸**：N≤10 但 M 可能较大，分支定界仍可能超时。缓解：匹配松弛 + 局部修复、缓存局部下界、按层分解。
6. **承诺的诚实性假设**：CCC 假设机器人如实报告承诺与进度；若存在恶意/故障机器人，可能伪造进度。缓解：承诺签名、与 v20 HPC 交叉验证、复用 CFC 的异常剔除与信誉。
7. **任务测度 μ 的错配**：成功率下界是相对于预注册 μ 的；部署分布偏移会使“下界”不再是部署成功率的界。缓解：预注册 μ、分层报告、分布偏移检测、保守支撑集。
8. **分配目标被“挑软柿子”**：CRA 可能通过选择容易的子任务来抬高 Φ，而完整任务仍未完成。缓解：覆盖约束、完整任务成功定义、独立审计。

## 8. 本轮最大风险

**一句话**：v21 的成功率下界严格依赖**预注册的环境分层 E 与任务测度 μ**；一旦部署中出现未枚举的共同失效层（例如新型反光、遮挡、网络分区组合），层内边际下界 ℓ_n(e) 会失效，而 Fréchet 公式仍会给出一个看似合理的 L——系统将以“已认证成功率”的名义系统性高估真实成功率。
