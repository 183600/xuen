# 第 55 轮（承接第 54 轮 v16+++；灵感循环新一轮第 1 轮；本轮灵感：「力觉传感」×「用户需求分析」）

> 第 54 轮把技能组合从“能力匹配”提升为“动作空间占用 α_S + 鲁棒性谱 ρ”的双证书，但动作空间仍只刻画了**运动学可达性**。本轮引入两个此前被压扁的维度：**力觉（接触力/力矩/触觉）** 是动作空间的“隐维”，**用户需求分析** 是把主观、模糊、个体相关的力语义转成可验证力契约的“逆问题”。核心矛盾：H22：技能在运动学上兼容，却在力域上冲突（一个技能要求 5N 稳定夹持，另一个要求 0.5N 柔性释放），组合执行时才暴露；H23：用户说“轻一点、稳一点、别捏碎”并不是一个数值阈值，直接把自然语言映射为力上限，会产生“形式正确、人不满意”的需求-力规格错配。

## 0. 直觉与动机

**灵感 1（力是动作空间的隐维 → 从 α_S 到 (α_S, β_S)）**
直觉：两个技能的动作覆盖完全一样，不代表它们能接续。抓取后要“递给人”，抓取技能占据的是“位置×姿态”，递出技能真正约束的是“接触力×柔顺度×力矩方向”。力觉传感把不可见的接触状态变成可测信号，因此技能应被描述为**力包络** `F_S(a) = {w ∈ W : β_S(a,w) ≥ θ_f}`，其中 `w=(f,τ)` 是六维力旋量。动作空间于是从 `A` 扩展为 `A × W`，组合的第一性约束变成**动作兼容 ∧ 力旋量兼容 ∧ 力过渡连续**。

**灵感 2（需求分析是力契约的逆问题 → 从“给阈值”到“接地 + 消歧”）**
直觉：用户需求不是客观真值，而是一个**待协商的分布**。需求分析要做的不是“猜一个数”，而是：抽取力语义线索（柔/稳/脆/滑）→ 识别硬约束与软偏好 → 主动提问把歧义压到可接受范围 → 产出带优先级的**力契约** `R_F=(W_req, w_cap, κ_req, π, ε_req)`。关键是把“轻一点”表示为**区间/可信集**而非点值，并显式记录歧义度；歧义未降到阈值以下就不允许出证书。

**灵感 3（力觉是需求分析的证据源 → 闭环校准）**
直觉：用户说“太硬了/还是有点滑”，本质上是在给力觉信号打偏好标签。力觉传感让“需求是否被满足”从主观问卷变成**可对照的力轨迹证据**。于是可以构建 `需求 → 力契约 → 执行力轨迹 → 用户反馈 → 契约更新` 的闭环；用户偏好模型从成对比较中学习，且能估计个体刚辨差 JND，避免把一个人的舒适阈值强加给所有人。

**灵感 4（力契约个性化与冲突协商）**
直觉：同一个“稳”，老人和儿童、玻璃杯和纸杯的力语义不同；多个需求（夹稳 vs 不捏碎 vs 快速）会互相冲突。应把需求分析产物看成**带优先级的约束系统**，先做需求-力可行性（RFF）检查：若 `W_req` 与技能力包络无交集，则不是“调参”，而是需求本身不可满足，必须回到用户处协商（放松优先级最低的软约束），而不是让规划器硬扛。

**灵感 5（金字塔扩展：力觉-需求层）**
直觉：在第 54 轮动作-协同层 `𝔸` 之上叠加 **力觉-需求层 `𝔽`**：`𝔽_0` 物理接触极限，`𝔽_1` 技能力包络，`𝔽_2` 用户力契约与偏好，`𝔽_3` 任务级力序列。跨层证书必须同时携带 `ρ`、`A_cert`、`F_cert`、`R_F`，形成**动作-鲁棒性-力-需求四元证书**。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（力觉剖面与力包络）**
设力旋量空间 `W ⊆ ℝ^6`，`w=(f,τ)`。技能 `S` 的力觉剖面 `β_S : A × W → [0,1]`，`β_S(a,w)` 表示在动作 `a` 下施加力旋量 `w` 的可执行置信度。**力包络** `F_S(a) = {w ∈ W : β_S(a,w) ≥ θ_f}`。安全裕度 `m_S(a,w) = dist(w, ∂F_S(a))`（到包络边界的加权距离）。

**定义 122（力旋量兼容性与力冲突）**
在共享动作 `a ∈ A_i ∩ A_j` 上，力兼容性
```
compat_w(S_i,S_j;a) = |F_i(a) ∩ F_j(a)| / |F_i(a) ∪ F_j(a)|
```
力过渡成本
```
c_w(S_i,S_j;a) = min_{w∈∂F_i(a), w'∈∂F_j(a)} ( ||w-w'||_{Σ^{-1}} + λ·t_settle(w,w') )
```
组合可判定条件在定义 116 基础上增加：`compat_w ≥ θ_w ∧ c_w ≤ τ_w`，其中 `τ_w` 为边端柔顺/力控带宽。若 `F_i(a) ∩ F_j(a) = ∅`，称**力冲突（force conflict）**；若交集非空但过渡所需力变化率超过 `τ_w`，称**力过冲冲突**。

**定义 123（需求-力契约与接地映射）**
力契约 `R_F = (W_req, w_cap, κ_req, π, ε_req, ctx)`：
- `W_req ⊆ W` 为可接受力旋量集（区间盒或椭球）；
- `w_cap` 为最大允许力幅值；
- `κ_req` 为期望柔顺度（逆刚度）；
- `π = (π_1,...,π_m)` 为约束优先级；
- `ε_req` 为允许违反概率；
- `ctx` 为任务/物体/用户上下文。

接地映射 `G_req : L × ctx → Δ(ℛ)` 把自然语言需求 `L` 映射为力契约分布。其**歧义度** `Amb(b) = H(b)`（后验熵）或归一化可信集体积。称需求**已接地**当且仅当 `Amb(b) ≤ θ_H` 且 `w_cap ≤ w_phys`。

**定义 124（需求-力可行性 RFF）**
给定技能 `S`、动作 `a`、契约 `R_F` 与最小安全裕度 `m_min`：
```
sat(R_F,S,a) = P_{w~U(W_req)}[ w ∈ F_S(a) ∧ m_S(a,w) ≥ m_min ]
RFF(R_F,S,a) = 1  ⟺  sat ≥ 1-ε_req ∧ max_{w∈F_S(a)}||f|| ≥ w_cap
```
多需求 `{R_F^k}` 时取联合可接受集 `W_∩ = ∩_k W_req^k`；若 `sat(W_∩,S,a) < 1-ε_req` 且不存在按 `π` 放松软约束后的可行子集，则判定**需求冲突**。

**定义 125（用户力偏好与个性化目标）**
用户 `u` 的潜效用 `U_u(w,ctx)`；成对问询 `q=(w_A,w_B)` 的回答模型
```
P(answer=A | θ_u) = σ( (U_u(w_A)-U_u(w_B)) / δ_u )
```
`δ_u` 为类 JND 的噪声尺度。偏好可接受集 `W_u = {w : U_u(w) ≥ u_0}`，满足间隙 `γ_u = d(W_req, W_u)`。个性化契约 `R_F^u = argmax_{R⊆W_req} E_{w~U(R)}[U_u(w)]`，并约束 `R ⊆ F_S(a)`。

**定义 126（力-需求联合证书）**
联合证书 `K = (ρ, A_cert, F_cert, R_F, θ_u, evidence)`：
- `ρ`、`A_cert` 承接第 53/54 轮；
- `F_cert = (F_core, F_buffer, δ_w)`，`F_core = ∩_k F_{S_k}(a_k)`，`F_buffer = F_core ⊕ B_{δ_w}` 为力不确定性缓冲；
- `R_F` 为已接地力契约，`θ_u` 为用户偏好模型参数；
- `evidence` 至少含力轨迹、标定日志、主动问询记录与反例。
若 `dom_J(T)=in ∧ δ_a<Θ_a ∧ RFF=1 ∧ γ_u ≤ Θ_u ∧ m_min>0`，则证书可部署。

## 2. 关键算法 伪代码

### IP-121 FSC（Force Space Characterization）

```python
def force_envelope(skill, A, W, safety_cap, budget):
    F, trace = {}, []
    for a in A:
        # 安全护盾：力上限随接触刚度自适应收紧
        cap = min(safety_cap, adaptive_cap(skill, a))
        gp = GPWrench(prior=skill.force_prior)
        while budget.remaining():
            w = gp.next_probe(a, cap, safe=True)   # 兼顾信息增益与安全
            ok, margin = skill.execute_safely(a, w, cap)
            gp.update(a, w, ok, margin); trace.append((a,w,ok,margin))
            if ok and margin < margin_floor:
                cap = 0.8*cap                    # 接近边界即回撤
        F[a] = {w for w,ok,m in trace if ok and m >= margin_floor}
    return F, trace
```

### IP-122 WCOM（Wrench-aware Composition）

```python
def build_force_composition_graph(skills, A, theta_a, theta_w, tau_e, tau_w):
    G = nx.DiGraph()
    for i,s1 in skills:
        for j,s2 in skills:
            if i==j: continue
            shared = A[s1] & A[s2]
            if not shared: continue
            a = argmax_a(shared, key=lambda a: jaccard(s1.alpha[a], s2.alpha[a]))
            if jaccard(s1.alpha[a], s2.alpha[a]) < theta_a: continue
            compat_w = wrench_jaccard(s1.F[a], s2.F[a])
            c_w = wrench_transition_cost(s1.F[a], s2.F[a])
            if compat_w < theta_w or c_w > tau_w:
                G.add_edge(i,j, conflict='force', compat_w=compat_w, c_w=c_w)
            elif transition_cost(s1,s2) <= tau_e:
                G.add_edge(i,j, cost=transition_cost(s1,s2), compat_w=compat_w,
                           c_w=c_w, F_overlap=s1.F[a] & s2.F[a])
    return G
```

### IP-123 REQ2F（Requirement-to-Force Grounding）

```python
def ground_requirement(L, ctx, belief, theta_H, max_questions):
    belief = update_from_language(belief, parse_force_cues(L))  # 软/硬/脆/滑
    while entropy(belief) > theta_H and max_questions > 0:
        q = argmax_q EIG(q, belief) / cognitive_cost(q)  # 主动问询
        ans = ask_user(q)
        belief = bayes_update(belief, q, ans)
        max_questions -= 1
    if entropy(belief) > theta_H:
        return ('needs_more_elicitation', belief)
    R_F = map_to_contract(belief, hard=hard_constraints, soft=preferences)
    return ('grounded', R_F, ambiguity=entropy(belief))
```

### IP-124 U2F（User-to-Force Preference Calibration）

```python
def calibrate_preference(user, queries, ctx):
    theta = prior_from_population(ctx)
    for (wA, wB, answer) in queries:
        lik = sigmoid((U(theta,wA,ctx)-U(theta,wB,ctx))/delta(theta))
```

### IP-125 RFF（Requirement-Force Feasibility）

```python
def rff_check(R_F, S, a, m_min, m_phys):
    if R_F.w_cap > min(m_phys, max_force(S.F[a])): return ('reject','force_cap')
    sat = monte_carlo(R_F.W_req, lambda w: w in S.F[a] and margin(S.F[a],w) >= m_min)
    if sat < 1 - R_F.epsilon: return ('reject','unreachable', sat)
    return ('ok', sat)

def resolve_conflict(reqs, S, a):
    for subset in relax_soft_by_priority(reqs):   # 按 π 从低到高放松
        W = intersect([r.W_req for r in subset])
        if rff_check(Contract(W,...), S, a)[0]=='ok':
            return ('negotiated', subset)
    return ('reject','requirements_infeasible')
```

### IP-126 FRC（Force-Requirement Certificate + Runtime Monitor）

```python
def force_requirement_certify(skill_seq, R_F, theta_u, gamma_u_budget):
    F_core = intersect([S.F[a] for S,a in skill_seq])
    F_buffer = minkowski_sum(F_core, ball(delta_w))
    if not F_core: return ('reject','force_conflict')
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| FSC | O(|A|·N_probe·|W|²)（GP 更新） | O(|A|·N_probe) | 安全护盾、包络边界可辨识 |
| WCOM | O(|S|²·|A|·|W|) | O(|S|²) | compat_w 阈值 sound、过渡成本单调 |
| REQ2F | O(Q·|ℛ|·|W|) | O(|ℛ|) | 主动问询信息增益、后验校准 |
| U2F | O(Q·|θ|) | O(|θ|) | 成对比较可辨识、JND 可估 |
| RFF | O(|W_req|·|F|)（采样） | O(|W|) | 采样覆盖、裕度下界 |
| FRC | O(|S|·|W| + T_mon) | O(|W|+T_mon) | 联合证书 sound、运行时监控完备 |

**正确性定理（Force-Grounded Requirement Soundness）**
承接第 54 轮 (A26)–(A28)；新增 **(A29)** 力包络在安全护盾下标定，边界误差 `ε_f`；**(A30)** 需求接地后验歧义 `H(b) ≤ θ_H`，真实契约落在可信集外的概率 `≤ ε_g`；**(A31)** 用户偏好模型误估概率 `≤ ε_u`，JND 可辨识；**(A32)** 接触仿真-真机差距 `≤ β_E`，运行时力监控漏检概率 `≤ ε_m`。则
```
P(安全 ∧ 用户接受部署) ≥ 1 - ε_f - ε_g - ε_u - β_E - ε_m - Σ_d(1-ρ_min(d))
```
关键：**力包络先于组合**、**需求先接地再出证书**、**偏好先校准再个性化**；任一环节未达阈值，证书只能判 `reject`，不得用“默认力阈值”兜底。

## 6. 本轮最大风险

**一句话**：力觉把动作空间补上了“接触”这一隐维、需求分析把“轻一点”变成了可验证的力契约，但整条链路把**主观需求当成可标定的客观真值**来对待；一旦需求接地把用户真正想要的“柔顺”误固化为一个力上限，系统会产出一个形式 sound、工程可部署、却在人看来“certified but wrong”的证书，甚至还可能因接触仿真差距而危险，因此必须坚持“需求可协商、歧义不达标不出证书、运行时力监控可否决”三道闸门，宁可要求用户再回答一个问题，也不把力阈值当成需求的真值。

| `U_u(w,ctx), δ_u` | 用户力效用与类 JND 噪声 |
| `γ_u=d(W_req,W_u)` | 需求与用户偏好的满足间隙 |

```python
def force_envelope(skill, A, W, safety_cap, budget):
    F, trace = {}, []
    for a in A:
        cap = min(safety_cap, adaptive_cap(skill, a))
        gp = GPWrench(prior=skill.force_prior)
        while budget.remaining():
            w = gp.next_probe(a, cap, safe=True)
            ok, margin = skill.execute_safely(a, w, cap)
            gp.update(a, w, ok, margin); trace.append((a,w,ok,margin))
            if ok and margin < margin_floor:
                cap = 0.8 * cap
        F[a] = {w for w,ok,m in trace if ok and m >= margin_floor}
    return F, trace
```

### IP-122 WCOM

```python
def build_force_composition_graph(skills, A, theta_a, theta_w, tau_e, tau_w):
    G = nx.DiGraph()
    for i,s1 in skills:
        for j,s2 in skills:
            if i==j: continue
            shared = A[s1] & A[s2]
            if not shared: continue
            a = argmax(shared, key=lambda a: jaccard(s1.alpha[a], s2.alpha[a]))
            if jaccard(s1.alpha[a], s2.alpha[a]) < theta_a: continue
            compat_w = wrench_jaccard(s1.F[a], s2.F[a])
            c_w = wrench_transition_cost(s1.F[a], s2.F[a])
            if compat_w < theta_w or c_w > tau_w:
                G.add_edge(i, j, conflict='force', compat_w=compat_w, c_w=c_w)
            elif transition_cost(s1, s2) <= tau_e:
                G.add_edge(i, j, cost=transition_cost(s1, s2), compat_w=compat_w,
                           c_w=c_w, F_overlap=s1.F[a] & s2.F[a])
    return G
```

```python
def ground_requirement(L, ctx, belief, theta_H, max_questions):
```

```python
def rff_check(R_F, S, a, m_min, m_phys):
    if R_F.w_cap > min(m_phys, max_force(S.F[a])):
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| FSC | O(|A|·N_probe·|W|²) | O(|A|·N_probe) | 安全护盾、边界可辨识、采样覆盖 ≥ 95% |
| WCOM | O(|S|²·|A|·|W|) | O(|S|²+|E|) | compat_w 阈值 sound、过渡成本单调 |
| REQ2F | O(Q·|ℛ|·|W|) | O(|ℛ|) | 主动问询信息增益、后验校准 |
| U2F | O(Q·|θ|) | O(|θ|) | 成对比较可辨识、JND 可估 |
| RFF | O(|W_req|·|F|) | O(|W|) | 采样覆盖、裕度下界 |
| FRC | O(|S|·|W| + T_mon) | O(|W|+T_mon) | 联合证书 sound、监控完备 |

**正确性定理（Force-Grounded Requirement Soundness）**
承接第 54 轮 (A26)–(A28)；新增 **(A29)** 力包络在安全护盾下标定，边界误差 `ε_f`；**(A30)** 需求接地后验歧义 `H(b) ≤ θ_H`，真实契约落在可信集外概率 `≤ ε_g`；**(A31)** 用户偏好模型误估概率 `≤ ε_u`；**(A32)** 接触仿真-真机差距 `≤ β_E`，运行时力监控漏检 `≤ ε_m`。则
```
P(安全 ∧ 用户接受部署) ≥ 1 - ε_f - ε_g - ε_u - β_E - ε_m - Σ_d(1-ρ_min(d))
```
关键：**力包络先于组合**、**需求先接地再出证书**、**偏好先校准再个性化**；任一环节未达阈值只判 `reject`，不允许默认力阈值兜底。

## 6. 本轮最大风险

**一句话**：力觉与需求分析把动作空间补上了“接触”隐维、把“轻一点”变成了可验证力契约，但整条链路把**主观需求当成可标定的客观真值**；一旦需求接地把用户真正想要的“柔顺”误固化为一个力上限，系统会产出形式 sound、工程可部署、在人看来却“certified but wrong”的证书，甚至因接触仿真差距而危险，因此必须坚持“需求可协商、歧义不达标不出证书、运行时力监控可否决”三道闸门，宁可让用户再回答一个问题，也不把力阈值当成需求的真值。
