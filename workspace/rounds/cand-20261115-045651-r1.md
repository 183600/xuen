# 第 70 轮（承接第 69 轮「FLUID-RAS 交互消歧闭环」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「可靠性」×「通用操作」）

> R69 给了系统一套漂亮的「不确定性卫生」：aleatoric 收紧，epistemic 去问/看/触，动作似然做标定不可吸收的第二意见，并用 J_FLUID 逐轮盖章。但它把两个词混在了同一张证书里：**安全**（这一轮不出事）与**可靠**（这一族任务、这一整个寿命内，反复做还能成）。J_FLUID 是**点态、同分布、单轮**的谓词；「可靠性」却是**上下文 × 任务族 × 时间**上的统计量。一台每一轮都通过安全证书的机器人，完全可能在一个没见过的任务族上十次里只成四次——而 R69 的证书对此一无所知。
>
> 第二个盲点更贴近「通用操作」：R69 的兜底是「慢下来、别动、去问」。对单一任务这是保守；对通用操作（新物体、新工具、新组合、跨本体）它可能既不安全也不有用——**有些场合没有可问的对象，慢下来也不会让成功率上升**。此时需要的不是一个刹车，而是一个**一定做得到、但能力更低的通用动作**：停、退、伸手、抓、放、递、呼救。
>
> 本轮两个灵感正好补上这两块：
> - **可靠性**：把「这一轮安全」升级为「这一族任务、这个寿命内，以置信度 1−δ 达到 ρ_req 的成功率」，并让可靠性随上下文条件化、随寿命被持续监测；
> - **通用操作**：把兜底从「慢/问」升级为一个**可验证的通用操作库 Π_go**——它们是任务无关的、低速保守的、可被低成本、可重复的测试充分认证的技能，为整个系统提供一条**可靠性下限（reliability floor）**。
>
> 核心命题：**可靠性不是顶层策略的置信度，而是「顶层概率能力 + 底层确定性技能」的复合；当上下文条件可靠性下界 \underline R_gen(c) 跌破任务契约 ρ_req 时，系统不是慢下来，而是把决策权交给能提供可靠性下限的通用操作；若连 Π_go 也达不到 ρ_req，则诚实地说「这件事我做不可靠」并交接。** 命名 **RELI-GO**（RELIability-Gated Generalist Operations）。
>
> 理论姿态：**R69 是 RELI-GO 在「ρ_req=0、关闭委派、关闭决策价值修剪、可靠性恒定」边界上的严格退化**；R68 再是 R69 的退化。安全侧不弱于 R69，能力侧则由通用操作库保住一条可证明的下限。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证、还能问什么」，R70 问「**这套操作在长期、在没见过的任务上到底有多可靠；不可靠时，我还能做哪些一定做得到的事**」。

## 0. 直觉与动机

**灵感 1（可靠性 → 安全是一个谓词，可靠性是一个分布）**
直觉：R68/R69 的证书像「这一口饭没毒」，可靠性问的是「连续吃一年会不会出事」。安全关心最坏单次事件，可靠性关心**重复抽样下的成功率、可用率与可恢复率**。二者不能互相替代：一台永远停机的机器人绝对安全，但任务可靠性为零；一台成功率 99% 的机器人仍可能在 1% 的尾部造成不可接受伤害。RELI-GO 把二者显式分开：安全包络仍由 R68/R69 认证，可靠性契约则回答「值不值得让它自主做」。这直接补上 R69 从未度量的维度。

**灵感 2（通用操作 → 任务族不是单点，平均值会骗人）**
直觉：通用策略 π_gen 在一个**任务族** 𝒯 上部署，部署分布 p(τ) 是混合的。用整体平均成功率 85% 去背书，会掩盖某个质量占 20% 的子族只有 40% 的事实；而失败恰恰集中在这些尾桶。可靠性必须是**上下文条件**的：R(c)=P(成功|c)，契约是「每个有足够部署质量的桶都 ≥ ρ_req」，而不是「平均 ≥ ρ_req」。这与 R69 的模态条件化同构，但对象从「动作模态」升级为「任务-上下文桶」。通用操作把这个问题推到极端：任务族是开集，尾部永远存在，所以「平均可靠」不是可靠。

**灵感 3（通用操作 → 兜底必须是一条动作，而不是一个形容词）**
直觉：R69 的「保守」是一个标量 λ；λ 再大也只是让同一个策略走得更慢。通用操作要求兜底本身是**可执行、可认证、可复用**的技能：停、退、伸手、抓、放、递、呼救。它们任务无关，因而能在大量任务上被反复测试；它们低速保守，因而容易被形式化包络覆盖。于是「可靠性下限」不是喊出来的，而是由一个小技能库的最差认证成功率**算出来的**。这带来一个漂亮的角色互换：R69 用交互消除顶部歧义以**使用**能力；R70 用通用操作提供底部下限以**兜住**能力。

**灵感 4（可靠性会漂移 → 证书有保质期）**
直觉：可靠性不是常数。减速器磨损、传感器老化、季节/光照变化、任务族漂移，都会让 R(c) 随时间下降；一张去年校准的可靠性证书今天可能已经过期。所以可靠性必须被**持续监测**：把每次成功/失败当作一条带时间戳的证据流，用 anytime-valid 的 e-process / CUSUM 监测「可靠性是否已跌破契约」，一旦拒绝零假设就触发维护（重标定、缩桶、重测、限制自主、交接）。这把「可靠性」从一次性认证变成一项**被维护的资产**——对应可靠性工程里的「可靠性增长 / 视情维护」传统。

**灵感 5（可靠性可被博弈 → 新威胁模型）**
直觉：一旦可靠性成为放行自主权的货币，就有了伪造动机：挑容易的测试集（benchmark gaming）、把失败样本从账本里漏掉（reporting bias）、用相关样本污染校准集（conformal poisoning）、把困难任务塞进数据稀少的尾桶让「宽界」冒充「高可靠」（bucket-boundary gaming）、或干脆把系统调成「永远走通用操作」来刷低风险（capability denial）。所以本轮必须同时交付：交换性检验、能力核算（不剥夺不变式）、校准集污染检测、桶定义审计。否则「可靠性」会退化成一张自欺欺人的报表。

## 1. 形式化定义（增量：定义 310–326）

**定义 310（RELI-GO 总览）** RELI-GO = (GPL, CCRC, RGD, RAL, RLL, RCM, CAP, DVK, XG, RAS-WM†)。四不变式：
(i) **实时流零学习写操作**（继承 R69 定义 293-i）；
(ii) **可靠性门控**：任何自主执行必须满足上下文条件可靠性下界 \underline R(c) ≥ ρ_req(c)，否则委派给通用操作或交接（定义 315）；
(iii) **不剥夺**：每次委派必须记录损失的能力与可靠性缺口；累计能力遗憾超预算即触发测试预算重分配或重训（定义 319）；
(iv) **交换性可审计**：可靠性证书只在交换性成立的支持域内有效；支持域外自动降级为「未认证」（定义 321）。

**定义 311（通用策略与通用操作库 GPL）** 通用策略 π_gen: 𝒪×𝒯 → Δ(𝒜)（继承 R69 的 FMP）。通用操作库 Π_go = {g_1,…,g_M}，每个 g 是任务无关技能（停、退、伸手、抓、放、递、呼救），带低速/低力保守参数与认证包络；其任务价值 v_g ≥ 0，可靠性 R_g(c) 由低成本、可重复、跨任务的测试估计。**可靠性下限** ρ_floor(c) = max_{g∈Π_go} \underline R_g(c)。

**定义 312（上下文-任务描述子与分桶）** 上下文 c = φ(o_t, e_τ, b_emb) ∈ 𝒞，由观测、任务嵌入与本体标识组成；分桶 ℬ = {B_1,…,B_K} 是 𝒞 上可审计的划分（Mondrian 分桶）。部署质量 m_b = P(c∈B_b)。**有效桶集** ℬ_+ = {b: m_b ≥ m_min}；尾桶（m_b < m_min）不做独立保证，按全局下界或拒答处理。桶定义本身受审计（防止边界博弈）。

**定义 313（可靠性泛函与任务契约）** R(c) = P(S=1 | c)，S 为任务成功。任务契约：∀b∈ℬ_+，R_b ≥ ρ_req(b)；并定义尾部风险 CVaR_β(R) = E[R | R ≤ VaR_β(R)] 作为「最差任务族」的补充指标。ρ_req 由风险等级给出（如 0.99 医疗递送、0.95 家用取放、0.90 仓储搬运）。

**定义 314（上下文条件可靠性认证 CCRC）** 对桶 b 的校准集 D_b = {(c_i,S_i)}，用 Clopper–Pearson（二值成功）或 conformal risk control（连续收益）构造成功率的单侧下界：
\underline R_b = 1 − UCB_{1−δ_b}(失败率; n_b)，
其中 δ_b = δ/|ℬ_+|（Bonferroni 同时覆盖）。保证：在桶内交换性下，P(∀b: R_b ≥ \underline R_b) ≥ 1−δ。数据不足的桶不发放证书（\underline R_b := 0 或走层级收缩，且标记「未认证」）。

**定义 315（可靠性门控委派 RGD）** 每步在候选 {继续 π_gen} ∪ Π_go ∪ {safe_stop, handover} 上求解：
a* = argmax_a E[V(a) | c]  s.t.  \underline R_a(c) ≥ ρ_req(c) 且 risk_safety(a) ≤ ε。
若 \underline R_gen(c) ≥ ρ_req：用 π_gen（能力优先）；否则选使任务进展最大且达标的 g∈Π_go；若 ρ_floor(c) < ρ_req：不假装可靠，执行 safe_stop 或 handover。**「慢」不再是兜底，而是候选动作之一。**

**定义 316（可靠性代数与预算分配 RAL）** 计划 π = (s_1,…,s_m) 的端到端可靠性用无分布假设的 Bonferroni 下界：R(π) ≥ 1 − Σ_i(1−R_i)，并集界对任意相关结构成立。给定任务目标 ρ_task，按最小化 Σ_i cost_i(ρ_i) s.t. Σ_i(1−ρ_i) ≤ 1−ρ_task 分配子目标可靠性预算（KKT：边际成本相等）。组合不可行（预算不够）⇒ 计划在可靠性上不可行，必须改计划或交接。

**定义 317（可靠性账本与漂移监测 RLL）** 账本 L 记录每条 (c_t, a_t, S_t, 证书版本, 校准集哈希)，只追加、哈希链、不可静默删除。对零假设 H_0: R(c) ≥ ρ_req 构造 Bernoulli 混合似然 e-process E_t；由 Ville 不等式，P_{H_0}(sup_t E_t ≥ 1/α) ≤ α，故可在任意停止时刻做有效拒绝。拒绝 ⇒ 触发维护。

**定义 318（可靠性中心维护 RCM）** 维护动作集 ℳ = {重标定, 缩桶/并桶, 补测, 重训, 限制自主, 人工交接}，各有成本与恢复收益。选择 m* = argmax_m [预期可靠性恢复 − 成本 − 停机损失]，且维护动作本身不得绕过安全包络。维护后证书版本递增，旧账本保留以做审计。

**定义 319（能力核算与不剥夺 CAP）** 委派造成的能力遗憾 regret_t = V(π_gen | c) − V(a_delegated | c)（按任务价值）。累计遗憾 Reg_T = Σ_t regret_t；不剥夺不变式：若 Reg_T/T > κ_reg 或委派率 > κ_go，系统必须 (a) 增加 π_gen 的测试/训练预算，或 (b) 向人类报告能力退化，**不得以「更安全」为名永久静默降级**。

**定义 320（决策价值信息动作 DV-K）** 信息动作 g 的价值不再只看熵降，而看它是否**改变委派/执行决策**：
DVoI(g) = E_{y~p(·|g,c)}[max_a V(a | c,y)] − max_a V(a | c)。
仅当 DVoI(g) > cost(g) 才交互。**R69 的熵 VoI 只问「知道了会不会更确定」，DVoI 问「知道了会不会改变做法」；前者是后者的必要非充分条件**——熵降但决策不变时 DVoI=0，R70 不问。

**定义 321（交换性门 XG）** 对当前 c，用支持域检测（密度比 / OOD 分数 / 桶内最近邻距离）判断 c 是否落在校准分布的支持域内。若不在：交换性假设失效，\underline R(c) 不具保证，令 \underline R(c) := 0（未认证），强制走 Π_go 或交接。这与 R69 的 MCG 同构：**不可信的可靠性估计不得驱动自主决策**。

**定义 322（通用操作的验证包络与跨本体迁移）** 每个 g∈Π_go 带 (前置条件 Pre_g, 不变式 Inv_g, 终止条件 Post_g, 参数包络 Θ_g) 与形式化/大量测试认证；跨本体用参数化包络 Θ_g(b_emb) 与可靠性偏移 ΔR_g(b_emb) 表达。委派只允许在包络内执行；包络外 g 作废，不做「近似可以」。

**定义 323（交互可靠性并入账本）** R69 的「问」本身有失败率：答非所问、拒答、延迟、投毒。定义交互可靠性 R_int(g) 与净信息增益 DVoI_net = R_int·DVoI − (1−R_int)·cost_fail；交互可靠性也入账本、也受漂移监测。**R69 把回答当真值，R70 把回答当一条有可靠性的证据。**

**定义 324（主动可靠性测试预算 ART）** 测试预算按「桶宽 × 部署质量 × 契约缺口」分配：优先测置信区间最宽且 m_b·(ρ_req−\underline R_b) 最大的桶（最需要也最影响决策的地方）。测试本身是信息动作，受 DV-K 与安全包络约束。

**定义 325（可靠性证书 J_RELI）** J_RELI = (J_FLUID, per_bucket_LCB, coverage_delta, exchangeability_ok, delegation_log_hash, capability_regret, ledger_head_hash, reliability_version)。Valid ⇔ Valid(J_FLUID) ∧ 同时覆盖率 ≥ 1−δ ∧ 交换性门通过 ∧ 委派/维护记录完整。

**定义 326（可靠性威胁模型 AIC-RELI）** ℰ_RELI = ℰ_FLUID × ℰ_reliability，其中 ℰ_reliability = {benchmark gaming（挑简单测试集）, reporting bias（漏记失败）, conformal poisoning（相关样本污染校准集）, bucket-boundary gaming（把困难任务塞进宽界尾桶）, capability denial（永久走兜底刷低风险）, silent degradation（漂移但账本不报）}。

```python
# IP-264 GPL：通用策略 + 通用操作库接口（继承 R69）
class GeneralistPortfolio:
    def __init__(self, pi_gen, go_library):
        self.pi_gen = pi_gen                 # R69 FlowMatchingPolicy
        self.go = go_library                 # {g: (Pre, Inv, Post, Theta, R_hat)}

    def candidates(self, c):
        yield ("gen", self.pi_gen, None)
        for g in self.go:
            if in_envelope(g, c): yield ("go", g, None)
        yield ("stop", safe_stop, None)
        yield ("handover", human_handover, None)

# IP-265 CCRC：上下文条件可靠性下界（Clopper–Pearson / CRC）
def reliability_lcb(bucket, calib, delta):
    n, fails = calib.count(bucket)
    if n < N_MIN[bucket]: return 0.0        # 数据不足 = 未认证
    return 1.0 - clopper_pearson_ucb(fails, n, delta / len(active_buckets))

# IP-266 RGD：可靠性门控委派（慢不再是唯一兜底）
def reliability_gated_dispatch(c, lcb, req, go_lib):
    if lcb["gen"] >= req and safety_ok("gen"):
        return "gen"                          # 能力优先
    feasible = [(g, value(g, c)) for g in go_lib
                if lcb[g] >= req and in_envelope(g, c) and safety_ok(g)]
    if feasible: return max(feasible, key=lambda t: t[1])[0]
    return "handover" if human_available(c) else "stop"

# IP-267 RAL：可靠性代数 + 预算分配
def plan_reliability(plan, R, rho_task):
    lb = 1.0 - sum(1.0 - R[s] for s in plan)       # Bonferroni，任意相关
    return lb, lb >= rho_task

def allocate_budget(plan, rho_task, cost):
    return solve_convex(min sum(cost[s](rho[s]) for s in plan),
                        s.t. sum(1 - rho[s] for s in plan) <= 1 - rho_task)

# IP-268 RLL：e-process 漂移监测（任意时刻有效）
def update_ledger(ledger, c, action, success, rho_req):
    ledger.append((c, action, success)); e = e_value(ledger, rho_req)
    if e >= 1.0 / ALPHA: return "DRIFT", trigger_maintenance(ledger)
    return "OK", None

# IP-269 RCM：可靠性中心维护
def maintain(state):
    return argmax(M, key=lambda m: expected_recovery(m, state)
                  - cost(m) - downtime(m))

# IP-270 CAP：能力核算（不剥夺）
def capability_accounting(regret_hist, T, kappa_reg):
    if sum(regret_hist) / T > kappa_reg:
        return "REPORT_CAPABILITY_LOSS"             # 不得静默降级
    return "OK"

# IP-271 DV-K：决策价值信息动作（修剪 R69 的无用追问）
def decision_voi(c, belief, budget):
    base = max(value(a, c) for a in actions(c))
    for g in info_candidates(c):
        if not budget.allow(g) or not safety_ok(g): continue
        after = expected_after_value(g, belief, c)
        if after - base > cost(g): return g         # 只有会改变决策才问
    return None

# IP-276 主闭环（R69 之上加「可靠性层」）
def RELI_GO_round(M, obs):
    # 1) R69 策略层：多模态 + 交互（信息动作现在按 DVoI 选）
    z, o = M.mtm.forward(...); c, U_cal, _ = M.cof.step(...)
    ctx = M.gpl.context(o, M.task, M.embodiment)
    lcb = M.ccrc.bounds(ctx, M.calib)               # 预计算，在线仅查表
    g = M.dvk.choose(ctx, M.belief, M.budget)       # DVoI，而非熵 VoI
    if g: M.cia.execute(g)
    # 2) 可靠性层：交换性 → 门控委派 → 安全认证
    if not M.xg.in_support(ctx): lcb = {k: 0.0 for k in lcb}
    choice = M.rgd.dispatch(ctx, lcb, M.req, M.gpl.go)
    if choice == "gen":
        A = M.fmp.sample(o, K=1)                    # R69 常规路径
    elif choice in M.gpl.go:
        A = M.gpl.go[choice].instantiate(ctx)       # 通用操作，包络内
    else:
        A = safe_stop()
    k = M.c_ras_wm.certified_prefix(A, ..., wm_preds)
    # 3) 执行、记账、漂移监测、能力核算
    S = M.execute_and_observe(A[:k])
    status, _ = M.rll.update(ctx, choice, S, M.req[ctx.bucket])
    if status == "DRIFT": M.rcm.maintain(M.rll)
    M.cap.update(M.value_gen(ctx) - M.value(choice, ctx))
    # 4) 证书 + 审计
    M.vqa_r.submit_async(choice, lcb, S, M.cap.regret())
    return k, choice, M.jreli.issue(ctx, lcb, S)
```

## 3. 推导

**假设** A104（桶内交换性：每个有效桶的校准样本与部署样本可交换）；A105（成功有界代理：存在与任务成功单调一致的有界奖励）；A106（通用操作包络可靠：每个 g 在包络内的物理风险与终止性有认证）；A107（漂移分段平稳：在 e-process 的检验窗内 R(c) 不低于 ρ_req，或发生可检测的下降）。

**引理 19（可靠性认证的样本复杂度）** 在 A104–A105 下，用 Clopper–Pearson 认证 R_b ≥ ρ 时，若校准中零失败，需 n_b ≥ log δ_b / log ρ ≈ (1/(1−ρ))·log(1/δ_b)。例：认证 99% 可靠性、桶级 δ_b=0.01，需约 459 次零失败；一旦观测到失败，所需样本量按 KL 散度进一步上升。系：**尾部桶（部署质量小、样本少）恰恰最难认证，也恰恰是可靠性最该被保证的地方**——这是 RELI-GO 的根本张力。

**引理 20（组合可靠性下界）** 对任意相关结构，R(π) ≥ 1 − Σ_i(1−R_i)（Bonferroni / 并集界）；该界在失败事件近似互斥时最紧，在完全正相关时最松。相较独立乘积 Π R_i，并集界不需要独立性假设，故对通用操作这种跨任务组合更可信。系：可靠性预算以失败概率为单位线性可加，因此子目标分配是凸问题（定义 316）。

**引理 21（e-process 的任意时刻有效性）** 在 A107 与 H_0: R(c) ≥ ρ_req 下，Bernoulli 混合似然 e-process 满足 P_{H_0}(sup_t E_t ≥ 1/α) ≤ α（Ville）。故可在看到任意长时间数据后拒绝 H_0，而不产生「多次偷看」的 α 膨胀。检测延迟的期望约为 KL(ρ_req ‖ ρ_alt)^{-1}·log(1/α)。系：可靠性监测不必等到固定批次结束，**证书可以随时被吊销**。

**定理 18（RELI-GO 严格包含 FLUID-RAS / R68）** 在 A104–A106 下：
(i) 若关闭决策价值修剪（用 R69 的熵 VoI）、令 ρ_req=0、Π_go=∅，则门控恒选 π_gen，RELI-GO 逐指令退化为 FLUID-RAS；若再关闭交互，则退化为 R68；
(ii) 若 \underline R_gen(c) ≥ ρ_req 且交换性成立，则 RELI-GO 使用与 R69 相同的 π_gen 路径；DV-K 只改变「问不问」，不改变 π_gen 的执行。它与 R69 的熵 VoI 不是简单子集关系：DV-K 剪掉「熵降但决策不变」，也可能保留「熵降小但决策关键」，但两者差异只落在交互选择上；
(iii) 若 \underline R_gen(c) < ρ_req，委派只在 \underline R_g ≥ ρ_req 的通用操作中进行；若 ρ_floor < ρ_req，则 stop/handover，**不会执行未认证的低可靠动作**。
因此 R68 ⊂ R69 ⊂ RELI-GO，安全侧不弱于 R69（在置信意义上），能力侧由 ρ_floor 给出可证明下限。

**定理 19（门控的可靠性保证）** 在 A104–A107 与同时覆盖率 ≥ 1−δ 下，以概率 ≥ 1−δ：(a) 任何被自主执行的动作满足真实 R_a(c) ≥ ρ_req(c)；(b) 端到端计划满足 R(π) ≥ 1−Σ(1−R_i)；(c) 若交换性门拒绝当前上下文，则不发放自主执行，最坏退回 safe_stop/handover。系：**可靠性证书是「带置信度的下界」，不是「平均成功率」**；它的失效模式是保守（拒绝自主），而不是过度自信。

**引理 22（能力剥夺的必要性）** 若省略 CAP，门控在 ρ_req 较高、π_gen 波动时可能长期委派到低价值通用操作，系统可靠但无用；且该退化不会被成功率指标发现（因为失败已被「不做」规避）。CAP 把「能力遗憾」变成一等公民，使得「安全但无用」必须显式报告，从而可被优化或审计。系：可靠性治理必须同时治理**过度信任**与**过度保守**两种失败。

## 6. 本轮最大风险

**一句话**：RELI-GO 的全部保证都挂在「桶内交换性 + 每桶足够校准样本」上，而**通用操作最危险的地方恰恰是样本最少的尾部桶**——在那里 Clopper–Pearson 界最宽、交换性最容易被分布漂移打破，系统要么因为「未认证」而过度拒答（可靠但无用），要么因为桶划分过粗而把尾桶失败藏进一个「平均达标」的宽桶（无用却自以为可靠）；**可靠性证书最可能在最需要它的地方悄悄失效，而它失效时看起来仍然像一张合格的证书。**

**次级风险与缓解**：
1. **尾部数据稀缺** → 层级收缩 + 主动测试预算 ART（定义 324）+ 尾桶按最坏全局下界处理；
2. **交换性破坏（OOD）** → XG 支持域门（定义 321），越界即未认证、走 Π_go/交接；
3. **能力剥夺 / 永久兜底** → CAP 不剥夺不变式 + 能力遗憾报告 + 定期重测（定义 319）；
4. **可靠性被博弈** → 账本哈希链 + 校准集污染检测 + 桶边界审计（定义 326）；
5. **组合界过保守** → 并集界给最坏情况保证；正相关场景可学习依赖上界收紧（可选，但不作为安全前提）；
6. **通用操作本身不通用** → 参数化包络 Θ_g(b_emb) + 跨本体偏移 ΔR_g + 包络外禁用（定义 322）。

# 第 70 轮产物 · 创新点清单 v1：RELI-GO（RELIability-Gated Generalist Operations：上下文条件可靠性认证 × 通用操作库可靠性下限的闭环；GPL×CCRC×RGD×RAL×RLL×RCM×CAP×DVK×XG×RAS-WM†）

> 承接第 69 轮 IP-253~263（FLUID-RAS）。R69 把不确定性一分为二（aleatoric / epistemic），并让系统学会「问」；它给出的是**点态、同分布、单轮**的安全证书 J_FLUID。但「可靠性」不是这一轮的谓词，而是**上下文 × 任务族 × 寿命**上的统计量：一台每轮都通过安全认证的机器人，仍可能在一个没见过的任务族上十次只成四次。与此同时，R69 的兜底「慢下来/别动/去问」在**通用操作**（新物体、新工具、新组合、跨本体）下可能既不可用也不安全——有些场合没有可问的对象，慢下来也不会提高成功率。
>
> 本轮把「安全」与「可靠」显式分开，并把兜底从标量收缩升级为一个**可验证的通用操作库 Π_go**（停、退、伸手、抓、放、递、呼救）：它们是任务无关、低速保守、可被低成本、可重复的测试充分认证的技能，为系统提供一条**可靠性下限 ρ_floor**。核心命题：可靠性 = 顶层概率能力 + 底层确定性技能；当上下文条件可靠性下界跌破任务契约时，系统不是慢下来，而是**委派**给通用操作；若连 ρ_floor 也不达标，则诚实交接。
>
> 命名 **RELI-GO**（RELIability-Gated Generalist Operations）。定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**这套操作在长期、在没见过的任务上到底有多可靠；不可靠时我还能做哪些一定做得到的事**」。
>
> 理论姿态：**R68 ⊂ R69 ⊂ RELI-GO**。R69 是 RELI-GO 在「ρ_req=0、关闭委派、关闭决策价值修剪、可靠性恒定」边界上的严格退化；安全侧不让步，能力侧由通用操作库保住一条可证明的下限。
>
> IP 编号：IP-264~IP-278（共 15 个），全部为 RELI-GO 核心组件。

## 2. 形式化定义（要点版）

**定义 310（总览与四不变式）** `RELI-GO=(GPL,CCRC,RGD,RAL,RLL,RCM,CAP,DVK,XG,RAS-WM†)`；零学习写操作继承；可靠性门控 `\underline R≥ρ_req`；不剥夺（委派必须记账）；交换性可审计（支持域外未认证）。

**定义 311（GPL 通用策略 + 通用操作库）** π_gen 继承 R69 FMP；Π_go 为任务无关技能（停/退/伸手/抓/放/递/呼救），低速保守、包络认证；`ρ_floor(c)=max_g \underline R_g(c)`。

**定义 312（上下文分桶）** `c=φ(o,e_τ,b_emb)`；Mondrian 分桶 `ℬ`；`m_b=P(c∈B_b)`；`ℬ_+={b:m_b≥m_min}`；桶定义受审计。

**定义 313（可靠性泛函与契约）** `R(c)=P(S=1|c)`；`∀b∈ℬ_+` 要求 `R_b≥ρ_req(b)`；补充尾部 `CVaR_β(R)`；ρ_req 按风险等级设定。

**定义 314（CCRC 上下文条件认证）** `\underline R_b = 1−UCB_{1−δ_b}(fail;n_b)`，`δ_b=δ/|ℬ_+|`；桶内交换性下 `P(∀b:R_b≥\underline R_b)≥1−δ`；数据不足则 `\underline R_b:=0`（未认证）。

**定义 315（RGD 可靠性门控委派）** `a*=argmax E[V(a)|c]` s.t. `\underline R_a(c)≥ρ_req(c)` 且安全；π_gen 达标则用 π_gen；否则选达标且价值最高的 g∈Π_go；`ρ_floor<ρ_req` 则 stop/handover。「慢」只是候选动作之一。

**定义 316（RAL 组合与预算）** `R(π)≥1−Σ(1−R_i)`（并集界）；子目标预算 `min Σ cost_i(ρ_i)` s.t. `Σ(1−ρ_i)≤1−ρ_task`；不可行则改计划/交接。

**定义 317（RLL 账本与漂移）** 哈希链、只追加；Bernoulli 混合似然 e-process；H_0 下 `P(sup_t E_t≥1/α)≤α`；任意时刻可拒绝并触发维护。

**定义 318（RCM 维护）** `ℳ={重标定,缩桶/并桶,补测,重训,限权,交接}`；`m*=argmax[预期恢复−成本−停机]`；维护不绕安全包络，证书版本递增。

**定义 319（CAP 能力核算）** `regret_t=V(π_gen|c)−V(a_delegated|c)`；`Reg_T/T>κ_reg` 或委派率 `>κ_go` ⇒ 增测/重训或报告，**禁止静默永久降级**。

**定义 320（DV-K 决策价值信息）** `DVoI(g)=E_y[max_a V(a|c,y)]−max_a V(a|c)`；`DVoI>cost` 才交互；熵 VoI 是必要非充分条件，R70 剪掉「熵降但决策不变」的追问。

**定义 321（XG 交换性门）** 密度比/OOD/最近邻距离判支持域；域外 `\underline R:=0`（未认证），强制 Π_go/交接。不可信可靠性估计不得驱动自主。

**定义 322（通用操作验证包络与跨本体）** 每个 g 带 `(Pre,Inv,Post,Θ_g)`；跨本体 `Θ_g(b_emb)` 与 `ΔR_g`；包络外 g 作废。

**定义 323（交互可靠性并入）** `R_int(g)` 与 `DVoI_net=R_int·DVoI−(1−R_int)·cost_fail`；交互本身入账本、受漂移监测。回答是「有可靠性的证据」，不是真值。

**定义 324（ART 主动测试预算）** 优先测「区间最宽 × 部署质量 × 契约缺口」最大的桶；测试是受 DV-K 与安全包络约束的信息动作。

**定义 325（J_RELI）** `(J_FLUID, per_bucket_LCB, coverage_delta, exchangeability_ok, delegation_log_hash, capability_regret, ledger_head_hash, reliability_version)`；Valid ⇔ J_FLUID 有效 ∧ 同时覆盖率 ≥1−δ ∧ 交换性通过 ∧ 记录完整。

**定义 326（AIC-RELI）** `ℰ_RELI=ℰ_FLUID×ℰ_reliability`；`ℰ_reliability={benchmark gaming, reporting bias, conformal poisoning, bucket-boundary gaming, capability denial, silent degradation}`。

```python
# IP-264 GPL：通用策略 + 通用操作库
class GeneralistPortfolio:
    def __init__(self, pi_gen, go_library):
        self.pi_gen, self.go = pi_gen, go_library      # {g:(Pre,Inv,Post,Theta,R_hat)}
    def candidates(self, c):
        yield ("gen", self.pi_gen)
        for g in self.go:
            if in_envelope(g, c): yield ("go", g)
        yield ("stop", safe_stop); yield ("handover", human_handover)

# IP-265 CCRC：上下文条件可靠性下界（离线预计算）
def reliability_lcb(bucket, calib, delta):
    n, fails = calib.count(bucket)
    if n < N_MIN[bucket]: return 0.0                # 未认证
    return 1.0 - clopper_pearson_ucb(fails, n, delta / len(active_buckets))

# IP-266 RGD：可靠性门控委派（慢不再是唯一兜底）
def reliability_gated_dispatch(c, lcb, req, go_lib):
    if lcb["gen"] >= req and safety_ok("gen"): return "gen"
    feasible = [(g, value(g, c)) for g in go_lib
                if lcb[g] >= req and in_envelope(g, c) and safety_ok(g)]
    if feasible: return max(feasible, key=lambda t: t[1])[0]
    return "handover" if human_available(c) else "stop"

# IP-267 RAL：组合界 + 预算分配
def plan_reliability(plan, R, rho_task):
    lb = 1.0 - sum(1.0 - R[s] for s in plan)        # Bonferroni，任意相关
    return lb, lb >= rho_task

# IP-268 RLL：e-process 漂移监测（任意时刻有效）
def update_ledger(ledger, c, action, success, rho_req):
    ledger.append((c, action, success)); e = e_value(ledger, rho_req)
    if e >= 1.0 / ALPHA: return "DRIFT", trigger_maintenance(ledger)
    return "OK", None

# IP-271 DV-K：只有会改变决策才交互
def decision_voi(c, belief, budget):
    base = max(value(a, c) for a in actions(c))
    for g in info_candidates(c):
        if not budget.allow(g) or not safety_ok(g): continue
        if expected_after_value(g, belief, c) - base > cost(g): return g
    return None

def RELI_GO_round(M, obs):
```

## 4. 推导

**假设** A104 桶内交换性；A105 成功有界代理；A106 通用操作包络可靠；A107 漂移分段平稳。

**引理 19（认证样本复杂度）** 零失败时 Clopper–Pearson 认证 `R_b≥ρ` 需 `n_b≥log δ_b/log ρ ≈ (1/(1−ρ))log(1/δ_b)`。例：99% 可靠性、δ_b=0.01 约需 459 次零失败；出现失败后按 KL 散度增加。系：尾桶最难认证，却最需要保证。

**引理 20（组合下界）** 任意相关结构下 `R(π)≥1−Σ(1−R_i)`；失败近互斥时最紧、完全正相关时最松；不需要独立性，故适合跨任务组合。系：可靠性预算以失败概率线性可加，分配为凸问题。

**引理 21（e-process 任意时刻有效）** H_0 下 `P(sup_t E_t≥1/α)≤α`（Ville）；检测延迟约 `KL(ρ_req‖ρ_alt)^{-1}log(1/α)`。系：证书可随时吊销，无需固定批次。

**定理 18（严格包含 FLUID-RAS / R68）** (i) 关闭 DV-K、令 `ρ_req=0`、`Π_go=∅` ⇒ 逐指令退化为 R69；再关闭交互 ⇒ R68。(ii) 若 `\underline R_gen≥ρ_req` 且交换性成立，走与 R69 相同的 π_gen 路径；DV-K 只改变「问不问」，不改变 π_gen 执行，且与熵 VoI 的差异只落在交互选择上。(iii) 若 `\underline R_gen<ρ_req`，只在达标的 Π_go 中委派；`ρ_floor<ρ_req` 则 stop/handover，绝不执行未认证低可靠动作。故 `R68⊂R69⊂RELI-GO`。

**定理 19（门控保证）** 同时覆盖率 `≥1−δ` 下，以概率 `≥1−δ`：(a) 自主执行动作的真实 `R_a(c)≥ρ_req`；(b) `R(π)≥1−Σ(1−R_i)`；(c) 交换性门拒绝时最坏退回 stop/handover。系：证书是「带置信度的下界」，失效模式是保守而非过度自信。

**引理 22（能力剥夺的必要性）** 无 CAP 时，高 ρ_req + π_gen 波动会导致长期低价值委派，系统可靠但无用，且成功率指标看不见（失败被「不做」规避）。CAP 把能力遗憾显式化，使「安全但无用」可被优化与审计。

## 7. 本轮最大风险

**一句话**：RELI-GO 的全部保证都挂在「桶内交换性 + 每桶足够校准样本」上，而**通用操作最危险的地方恰恰是样本最少的尾部桶**——那里界最宽、交换性最容易被漂移打破，系统要么因「未认证」过度拒答（可靠但无用），要么因桶划分过粗把尾桶失败藏进「平均达标」的宽桶（无用却自以为可靠）；**可靠性证书最可能在最需要它的地方悄悄失效，而失效时看起来仍像一张合格证书。**

**次级风险与缓解**：尾桶数据稀缺（层级收缩 + ART + 最坏全局下界）；交换性破坏（XG 门，越界未认证）；能力剥夺（CAP 不剥夺 + 遗憾报告 + 重测）；可靠性博弈（哈希账本 + 校准集污染检测 + 桶边界审计）；组合界过保守（并集界保证，正相关时可选收紧）；通用操作不通用（Θ_g(b_emb) + ΔR_g + 包络外禁用）。
