# 第 14 轮（新灵感循环第 1 轮；本轮灵感：「推理延迟」×「续航能力」）

> **基线**：第 13 轮 MetricVoiceGauge-NCD-HUTD（定义 583–594；引理 113–121；实验 E627–E646）。
> 本轮纪律：**不推倒 v13**。v13 的 AIO/RTIC、CPD/DGC、DDL/RTCR 与 `Exec_v13⊆Exec_v12` 全部保留；v12/v11/v10/v9/v8 的模块、证书与九不变式原样继承。四个新组件——PLG（功率—延迟治理器）、MEC（任务续航证书）、ELPL（时能帕累托阶梯）、SR（可持续性路由器）——一律以**中立元**接入，失效即严格退回 v13（引理 128），再沿 v13→v12→…→v6 退化。本轮只做三件事：把"延迟"从固定 WCET 改写为**功率状态条件下的可证延迟**；把"续航"从剩余电量改写为**带返回储备的任务能力证书**；把 v13 的一维时间阶梯改写为**时间—能量二维帕累托阶梯**，使系统在低电量、热节流与老化下仍有可证的退路。

## 0. 直觉与动机

**灵感 1（推理延迟 → 延迟是功率状态的函数，且会跨帧借债）**
直觉：v13 已经把"实时"做成逐帧截止期证书，但 RTIC 仍隐含一个静态假设：WCET 是硬件的固定属性。真实机器人不是这样。电量下降会带来电压跌落与降频，温度升高会触发热节流，电池老化会抬高内阻，重载荷会让同一段推理多花几十毫秒。于是同一个学生、同一帧输入，在 80% 电量时 p99 是 22ms，在 15% 电量加高温时可能变成 35ms。更糟的是，**为了赶上当前帧截止期而提高功率，会同时制造热量与电量透支，反过来抬高未来帧的延迟**。这就形成了一个 v13 看不见的循环：今天靠"超频/大模型"按时，明天因热与低电量而超时。核心创新：**功率—延迟治理器（Power–Latency Governor, PLG）+ 延迟债证书（Latency Debt Certificate, LDC）**。PLG 把功率状态抽象成可证包络，RTIC 只在包络内有效；LDC 把"向未来借的毫秒"记成有上限、可偿还的账。关键反直觉点：**实时性不是把每一帧都跑满，而是保证未来帧仍然跑得动**；截止期证书必须带一个"功率状态有效期"，离开包络就必须重新认证或回退，而不能沿用旧 WCET。

**灵感 2（续航能力 → 不是剩余电量，而是有证书的任务完成能力）**
直觉：电量百分比是最容易被误读的指标。60% 电量在一个平坦、轻载、近距离的任务里很充裕；在爬坡、重载、需要多次深推理且必须返回充电座的任务里可能根本不够。续航能力不是"还能运行多久"，而是"在剩余任务、最坏推理负载与安全返回约束下，还能不能完成并回到安全状态"。核心创新：**任务续航证书（Mission Endurance Certificate, MEC）**。MEC 用单侧上界估计剩余任务所需能量，显式拆出三块互不挪用的储备：任务能量 `E_mission`、安全停靠/恢复储备 `E_safe`、返回/对接储备 `E_ret`。只有 `E_rem` 的下置信界覆盖三者之和，系统才被认证为"续航可行"。关键反直觉点：**续航不是电池的属性，而是"任务 + 策略 + 功率状态"的联合属性**；同一个电量，换一个更省电的授权档就可能从不可行变可行，换一个更激进的学生则相反。

**灵感 3（推理延迟×续航能力 → 时能帕累托阶梯与跨帧可持续路由）**
直觉：v13 的 DDL 只按延迟给学排档：算得越多、放行越多、耗时越长。但"快"不等于"省"：提高时钟或换大模型可以更快，却更耗电、更热；一个更慢但更省电的档位，可能在任务末期才是唯一可持续的选择。于是学生族不应是一维时间阶梯，而应是**时间—能量二维平面上的帕累托链**：每一档同时标注 `(w_i,e_i)`，授权集仍单调嵌套，但只有不被另一档在时间和能量上同时支配的档才允许部署。运行时路由器在 `(B_time,B_energy,debt)` 三元预算下选"当前付得起、且不侵占返回储备"的最高授权档。核心创新：**时能帕累托阶梯（Energy–Latency Pareto Ladder, ELPL）+ 可持续性路由器（Sustainability Router, SR）**。这把"实时"和"续航"合成同一个对象：**一条以时间与焦耳为双坐标的证书族**。路由器不是选"今天最快"，而是选"任务结束时还能安全回来的最高档"。

**四者如何统一**
统一为 **v13 实时实现层之上的可持续性层**：v12 回答"语义上允许什么"，v13 回答"本帧毫秒预算内能实现多少"，v14 回答"在整个任务时域与能量预算内，哪些实现仍然可持续"。PLG 把 v13 的 RTIC 条件化到功率包络并记延迟债；MEC 把能量预算提升为带返回储备的任务级证书；ELPL 把学生族从一维时间链扩成二维帕累托链；SR 在时间、能量、债务三元约束下选档、节能、返航或安全塌缩。共享状态 `ζ_sus=(B_time,B_energy,E_safe,E_ret,ρ,d_t,i*,mode)`。**PLG 回答"这个延迟证书现在还有效吗"，MEC 回答"还剩多少可花且必须留多少"，ELPL/SR 回答"这一帧及余下任务该跑到哪一档"**。四者不是四个节能补丁，而是"功率条件—任务续航—时能路由"的可持续实现链。

## 1. 研究问题（轮次升级版）

- **Q1（功率状态下的延迟可证性）**：如何定义功率状态包络，使 WCET/RTIC 在电量、温度、老化与负载变化下仍然 sound？"延迟债"应如何度量、封顶与偿还，才能既不保守到频繁降档，又不出现热—电—延迟的正反馈？功率状态离开包络时，如何与 v13 的中止点/回退语义无缝衔接？
- **Q2（续航的可证语义）**：如何把"续航能力"定义成带返回储备的任务级单侧证书？剩余任务能量上界、推理能量、地形/载荷与返回路径如何统一核算？共形/鲁棒能量证书在电池老化、温度模型误差与任务分布漂移下还能保持吗？MEC 失效时如何退化为"只返航/只停靠"而不是继续赌？
- **Q3（时能阶梯与可持续路由）**：如何训练/构造授权单调、资源单调的二维帕累托学生链？二维预算下"当前帧最优"与"任务期末仍可行"何时冲突？路由器如何在未知未来负载下做在线选档、预留返回能量、决定充电/返航，并使"截止期—续航—活动性"三者可解释地折中？
- **Q4（与 v13 的兼容与活性）**：能量约束会不会绕过 v13 的 TGC/DGC/四重证书？低电量时 SR 是否会把可行集清空、导致频繁 `a_ask` 或"永久返航"？MEC 的保守性会不会让系统在 60% 电量就停止工作？新增模块能否守住 50Hz/p99≤22ms 与能量开销，并严格退回 v13？

## 2. 设计原则（在 P22–P24 基础上新增 P25–P27）

**P25 功率状态条件律（Latency Is Power-State Conditioned）**
任何 RTIC 都必须绑定一个功率状态包络 `P_env`；只有当实际 `ρ∈P_env` 且延迟债 `d_t` 计入后仍满足截止期，RTIC 才有效。包络外不得沿用旧 WCET，必须重新认证、降档或执行认证回退。**功率状态是延迟证书的前置条件，不是事后解释。**

**P26 续航返回储备律（Endurance Includes Return Reserve）**
续航能力必须表述为"剩余任务 + 安全恢复 + 返回/对接"的单侧可行证书。`E_safe` 与 `E_ret` 是硬预留，任何性能档、任何蒸馏学生、任何"再跑一帧"都不得挪用；电量百分比本身不构成续航证据。**可以少做任务，不可以回不来。**

**P27 跨帧延迟债有界律（Bounded Cross-Frame Borrowing）**
允许为当前帧借用未来时间，但借用必须记入 `d_t`、有硬上限 `D_debt`、并在低功率/空闲时显式偿还；禁止用"下一帧会更便宜"的假设无限透支。若 `d_t>D_debt`、温度越界或电量跌破返回储备，只能沿阶梯向更保守方向移动、进入节能/返航模式或 `a_ask`。**实时性是对未来的承诺，不是对未来的借款。**

## 3. 与基线的接口（如何退化）

- PLG 失效 ⇒ 功率状态固定为标称包络、`d_t≡0`，RTIC 退化为 v13 静态 WCET 证书，**等价 v13 实时路径**；
- MEC 失效 ⇒ 不设任务级能量上限与返回储备，只保留低电量硬阈值，**等价 v13 + 低电量看门狗**；
- ELPL 失效 ⇒ 学生族退回 v13 的一维时间 DDL，能量只作事后过滤，**等价 v13 阶梯 + 能量后验检查**；
- SR 失效 ⇒ 由 v13 RTCR 按时间选档，能量只在执行前做一次硬检查，**等价 v13 路由路径**；
- 四者全失效 ⇒ MetricVoiceGauge-NCD-HUTD v13（引理 128），再沿 v13 退化链退回 v12/v11/v10/v9/v8/v7/v6；
- **安全继承**：PLG 只条件化/缩小 RTIC 的有效域，MEC 只增加能量可行性约束，ELPL 只在教师授权集内做嵌套，SR 只做选档与回退。四端口均不能新增授权、不能放宽 v13 证书阈值；`Exec_v14⊆Exec_v13⊆Exec_v12` 由引理 127 保证。

## 4. 预期贡献

1. **功率状态条件下的延迟证书与延迟债**：把 v13 的"逐帧截止期"升级为"功率包络内可证、跨帧不透支"的延迟语义，解决低电量、热节流与老化下 RTIC 静默失效的问题；
2. **任务续航证书**：把"续航"从电量读数改写为带安全/返回储备的任务级单侧证书，给出能量核算、共形覆盖与失效退化，填补"续航不可证"的空白；
3. **时能帕累托阶梯与可持续路由**：把学生族从一维时间链扩成授权单调、资源单调的二维帕累托链，使系统能在当前截止期与任务末期可行性冲突时显式折中，而不是靠"电池还够"的直觉；
4. **语义层—实时层—可持续层的三层分离**：v12 管"允许什么"，v13 管"本帧能实现多少"，v14 管"整个任务能否可持续地实现"；用 `Exec_v14⊆Exec_v13` 把节能与安全解耦；E647–E666 覆盖功率包络、延迟债、续航覆盖、二维嵌套、热/老化压力、端到端与消融。

## 5. 本轮最大风险

**一句话**：MEC 的能量模型是在标称电池、常温与已知任务分布上校准的，而真实系统的电池老化、低温内阻上升、重载地形与热节流会让"剩余任务能量上界"被系统性低估；路由器为守住每一帧截止期不断花掉本应留给返回的能量，直到某一帧仍然按时、账面仍然平衡，却已经没有足够的电回到安全区——即**每帧都实时、每笔能量都记账、任务却回不来的"可持续性幻觉"**。

# 第 14 轮产物 · 创新点清单 v14：**MetricVoiceGauge-NCD-HUTDE**（Metric Voice Gauge with Norm Grounding, Contact Dexterity, Causal Attribution, Harmonic Compliance, Universal Skills, Transfer Certification, **D**eadline-aware **D**istillation & **E**ndurance）

> 背景：第 13 轮 MetricVoiceGauge-NCD-HUTD（定义 583–594；引理 113–121；实验 E627–E646），其基线为第 12 轮 MetricVoiceGauge-NCD-HUT。
> 本轮灵感：「推理延迟」×「续航能力」
> **继承纪律**：MetricVoiceGauge 九不变式全部保留；v13 的 AIO/RTIC、CPD/DGC、DDL/RTCR 与 `Exec_v13⊆Exec_v12`、v12 的 USG/TGC/BAA/GAGP/UC、v11 的 HAS/HCC/HATD/HDT、v10 的 NGE/DSL/CC/CWM/CAE/NCP、v9 的 AC/MW/ID 与 v8 的 DA/SPR/Cal 原样保留。四个新组件均为**可选增强**：任一不可用 ⇒ 注入中立元；四者全不可用 ⇒ 严格等价退回 v13（引理 128），再沿 v13 退化链退回 v12/v11/v10/v9/v8/v7/v6。v14 是 v13 之上的**可持续性层**，只决定"任务时域内能否继续安全地实现"，绝不新增授权、绝不放宽任何既有证书。

**定义 595（功率状态与可证包络 Power-State Envelope）**
```
ρ = (soc, V, T, age, load) ∈ P
P_env = { ρ : soc_min ≤ soc ≤ soc_max , T_min ≤ T ≤ T_max ,
              age ≤ age_max , load ≤ load_max }
```
对每个功率状态单元 `c⊆P_env` 预标定保守延迟表 `W_c^max` 与能量表 `E_c^max`。要求在同一单元内对任意 `x`：
```
W(x;ρ) ≤ W_c^max(x),   E(x;ρ) ≤ E_c^max(x),   ∀ρ∈c .
```
若实际 `ρ∉P_env`，或某传感器使 `ρ` 不可辨识，则所有依赖 `ρ` 的证书立即标记为**未认证**，不得沿用上一帧的 `W_c^max`。`P_env` 是延迟与续航证书的**共同前置条件**，不是运行日志。

**定义 596（功率条件化实时推理证书 RTIC_ρ）**
```
RTIC_ρ = ( D, δ_t, {(w_k(ρ),q_k)}_{k=0..m}, B_safe, fallback ; P_env, d_t )
```
有效当且仅当：
1. `ρ∈P_env`，且对包络内最坏状态有 `P(latency + d_t ≤ D) ≥ 1−δ_t`；
2. 每个可中断档 `k` 满足 `Acc_k⊆Exec_v13` 且 `q_k≥q_floor(D)`；
3. 无档能在 `D` 内完成时执行 `fallback∈P^sus`，**不得执行迟到结果**；
4. `Σ_k w_k(ρ) + d_t + overhead ≤ B_time`，且 `B_safe` 硬预留、不得被性能模块挪用。
与 v13 定义 584 的唯一区别是：`w_k` 从常数变为 `w_k(ρ)`，并显式加入延迟债 `d_t` 与包络条件 `P_env`。离开包络时 RTIC_ρ **失效**，而不是"近似继续成立"。

**定义 597（延迟债证书 Latency Debt Certificate, LDC）**
把"当前帧提高功率/换大模型所借的未来时间"记为延迟债：
```
d_{t+1} = clip( d_t + κ·(e_t − e_ref)_+ − r_t , 0 , D_debt )
```
其中 `e_t` 为本帧推理能量、`e_ref` 为标称低功率参考能量、`κ` 为由热/电压/老化联合标定的保守"每焦耳延迟膨胀系数"（ms/J），`r_t≥0` 为低功率/空闲时的偿还速率（ms/帧）。证书 `LDC=(κ,r_t,D_debt,calib)` 有效当且仅当 `κ` 与 `r_t` 在硬件在环标定中给出单侧保守界，且路由器强制
```
d_t + κ·(e_t − e_ref)_+ ≤ D_debt .
```
若下一帧预计违约，必须在本帧选择更低功率档，而不是把 `clip` 当作"自动合法化"。

**定义 598（任务续航证书 Mission Endurance Certificate, MEC）**
对剩余任务集 `H`、当前策略类 `π_sus` 与功率包络 `P_env`，定义
```
MEC = ( H, Ê_req, E_safe, E_ret, α_e, δ_age, support )
```
有效当且仅当：
1. `Ê_req` 是 `E_req(H;π_sus,ρ)` 的单侧上界，覆盖推理、运动、载荷、地形与返回前任务消耗；
2. 对电池老化/容量衰减 `δ_age` 与温度模型误差已做保守膨胀；
3. `E_rem^low := E_rem − δ_soc` 满足
```
P( E_req(H;π_sus,ρ) + E_ret + E_safe ≤ E_rem^low ) ≥ 1−α_e ;
```
4. `support` 覆盖当前任务/地形/负载分布；超出支撑时 `MEC` 失效，只能进入返航/停靠模式。
`E_safe` 用于安全停止、柔顺与恢复；`E_ret` 用于返回充电座/安全区。两者是**硬预留**，不是优化变量。

**定义 599（时能帕累托阶梯 Energy–Latency Pareto Ladder, ELPL）**
```
L_el = ( S_0, S_1, …, S_m ; (w_0,e_0) ⪯_el … ⪯_el (w_m,e_m) ; θ_i=U_{d,i} )
Acc_i = { (x,a) : m_{S_i}(x,a) ≥ θ_i }
```
要求：
1. `Acc_0⊆Acc_1⊆…⊆Acc_m⊆Acc_T`（v13 的授权单调性不变）；
2. 对链上相邻档，`w_i≤w_{i+1}` 且 `e_i≤e_{i+1}`；
3. 任何被另一档在 `w`、`e`、授权三方面同时支配的候选学生必须被裁剪，不得部署；
4. `S_0` 是**无需学习的零假设安全回退**（安全停/柔顺/`a_ask`），其能耗只含反射与通信，且 `w_0,e_0` 为链首。
若独立学生不满足链序，用**并集门 + 帕累托裁剪 + 单调罚项**强制：
```
Acc_i ← ∪_{j≤i} Acc_j ,   e_i ← max_{j≤i} e_j ,   w_i ← max_{j≤i} w_j
```
宁可把一个档做慢、做省，也不允许"授权更大但资源更少"的不可持续档进入部署。

**定义 600（可持续路由状态）**
```
ζ_sus = ( B_time, B_energy, E_safe, E_ret, ρ, d_t, i*, mode )
mode ∈ {sustain, conserve, return, fallback}
```
其中 `B_energy := E_rem^low − E_safe − E_ret` 是本帧可用于任务的能量预算；`B_time` 继承 v13（含 `B_safe`）。SR 只读 `ζ_sus` 选档；档位证书由 PLG/MEC/ELPL 预先产生。

**定义 601（升级定义 592 的时能可持续选择）**
```
max_g  E[Progress(g)]
       − λ_risk·(U_gap(g)+U_dis(g))
       − λ_time·E[latency(g)]
       − λ_energy·E[energy(g)]
       − λ_ask·E[false_reject(g)]
s.t.   v11/v12 物理/接触/谐波/规范/gap 证书全部有效
       v13 RTIC_ρ 有效，ρ∈P_env，d_t + κ(e−e_ref)_+ ≤ D_debt
       E_req(g)+E_safe+E_ret ≤ E_rem^low
       Σ_seg(U_gap+U_dis) ≤ B_total
       W_p99(g)+d_t ≤ D ,  P^sus(g) ≠ ∅
       Acc_i(g) ⊆ Acc_T(g)，替换仅在已认证等价类内
```
`λ_energy` 是能量价格，不是"把焦耳折算成毫秒"的兑换率；时间与能量始终分账，二维阶梯只提供**合法离散折中点**。若某组合能量超预算但信息价值高，只能转为离线采样/校准，不能执行任务段。

**定义 602（可持续安全回退集 P^sus）**
在 v13 的 `P^rt` 基础上，
```
p ∈ P^sus ⇔ ∃π_f : π_f∈Exec_v13
             ∧ w(π_f)+d_t ≤ B_time(p)
             ∧ e(π_f) ≤ E_safe(p)+E_ret(p)
             ∧ MEC 在 π_f 后仍有效
             ∧ 执行 π_f 不破坏 I_c、I_h 与规范硬约束
```
要求 `P^sus≠∅` 且至少含一个**无需学习证书**的零假设回退（停/柔顺/`a_ask`），以及一个能量可行的返回/对接回退（若当前任务允许）。可执行段的必要条件升级为 `P^g≠∅ ∧ P^rt≠∅ ∧ P^sus≠∅`。

**定义 603（中立元表 v14 扩展）**

| 新组件 | v^⊥ | 等价退化点 |
|---|---|---|
| PLG | 标称包络、`d_t≡0`、RTIC 用 v13 静态 WCET | Level-4（v13 实时路径） |
| MEC | 无任务级能量证书，仅低电量硬阈值 | Level-3（v13 + 低电量看门狗） |
| ELPL | 退化为 v13 一维时间 DDL，能量仅后验过滤 | Level-2（v13 阶梯 + 能量检查） |
| SR | 由 v13 RTCR 按时间选档，能量仅执行前硬检查 | Level-1（v13 路由 + 低电量看门狗） |

**定义 604（四预算不可挪用 Four-Budget Non-Fungibility）**
```
B_total = B_transfer + B_distill          # 真实侧误差预算，见 v13 引理 121
B_time  = B_safe + B_infer                # 安全切片硬预留
E_usable = E_mission + E_safe + E_ret     # 能量三重储备
```
时间、迁移、蒸馏、能量四类预算各自独立，**不得互相冲抵**：不能拿返回储备买当前帧延迟，不能拿迁移预算补蒸馏间隙，也不能用"省电"名义放宽任何 v13 证书。二维阶梯上的 `(w_i,e_i)` 是**合法折中菜单**，不是预算间兑换器；任一预算耗尽时，唯一允许的动作是沿阶梯更保守、进入节能/返航或 `a_ask`。

**定义 605（可持续执行策略与安全继承）**
```
π_sus(x;B_t,B_e,d) = argmax_{a∈Acc_{i*}(x)} value(a)
i* = max{ i : w_i+d ≤ B_t−B_safe , e_i ≤ B_e , RTIC_ρ,i 有效 , MEC 有效 }
Exec_v14 = { a : a∈Acc_{i*}(x) ∧ v13 证书有效
                ∧ ρ∈P_env ∧ d_t≤D_debt
                ∧ E_req+E_safe+E_ret ≤ E_rem^low
                ∧ P^sus≠∅ }
```
要求对所有 `x,B_t,B_e,d` 有 `π_sus(x;B_t,B_e,d)∈Exec_v13(x)`。SR 的"节能/返航"只是实现 `π_sus` 的方式：学生放行仅当属于 `Acc_{i*}`；否则在剩余时间/能量足够时由教师 anytime 验证，验证不完成或能量不足以返回则退回 `P^sus`。

**定义 606（能量账本与任务时域核算 Energy Ledger）**
能量账本按技能/段维护单侧上界：
```
Ê_req(H) = Σ_{s∈H} ( ê_infer(s;ρ,i) + ê_motion(s;terrain,payload) + ê_comm(s) ) + Ê_ret
```
其中 `ê_infer` 取当前授权档与功率状态包络内的保守上界，`ê_motion` 取地形/载荷模型上界，`Ê_ret` 取返回路径与对接的上界。账本只允许**向上修正**：实测超界时抬升后续上界并触发重校准，不允许用历史平均值下调。每个任务段执行后做 `E_rem ← E_rem − e_actual`，并检查 `MEC` 是否仍有效。

## 2. 形式化升级（要点）

**升级定义 584（RTIC）** 用定义 596 的 `RTIC_ρ` 替换：增加 `ρ∈P_env`、`w_k(ρ)`、`d_t`，其余截止期/质量下界/回退结构不变。

**升级定义 587（DDL）** 用定义 599 的 `L_el` 替换：授权嵌套不变，增加二维资源链序与帕累托裁剪；`S_0` 仍为零学习安全回退。

**升级定义 590/602（回退集）** `P^rt` 升级为 `P^sus`，增加能量可行性与返回储备；四类中止点分别回答"能不能导航停""接触能不能安全停""谐波能不能耗散停""真实侧有没有按时且能量可行地回到安全区"。

**升级定义 592（选择）** 见定义 601：增加 `−λ_energy·E[energy]`、`E_req+E_safe+E_ret≤E_rem^low`、`d_t` 与 `P^sus≠∅`；不改变 v13 的任何证书项。

**升级定义 593（三预算）** 见定义 604：扩为时间/迁移/蒸馏/能量四预算，四者不可挪用。

**升级定义 594（实时策略）** 见定义 605：`π_rt` 升级为 `π_sus`，并给出 `Exec_v14⊆Exec_v13`。

**升级定义 580（中立元）** 见定义 603；四个中立元注入后调用序列与 v13 逐位一致。

# IP-379 PowerLatencyGovernor：功率状态包络 + 延迟债
class PowerLatencyGovernor:
    def __init__(self, envelope, wcet_table, kappa, repay_rate, debt_cap):
        self.env, self.W = envelope, wcet_table
        self.kappa, self.rate, self.D_debt = kappa, repay_rate, debt_cap

    def observe(self, battery, thermal, age, load):
        rho = PowerState(battery.soc, battery.voltage, thermal.temp, age, load)
        if not self.env.contains(rho):
            return rho, False, None              # 证书未认证：只允许回退
        cell = self.env.cell_of(rho)
        return rho, True, self.W[cell]           # 包络内保守 WCET 表

    def condition(self, rtic, rho, d_t):
        if not self.env.contains(rho):
            return None                          # 包络外：RTIC_rho 失效
        w = rtic.wecet_for(rho) + d_t
        return rtic if w <= rtic.D else None

    def update_debt(self, e_frame, e_ref, d_t):
        grow = self.kappa * max(0.0, e_frame - e_ref)
        if d_t + grow > self.D_debt:             # 不允许把 clip 当合法化
            return None, "debt_cap"
        return max(0.0, d_t + grow - self.rate), "ok"


# IP-380 MissionEnduranceCertificate：任务级能量单侧证书
class MissionEnduranceCertificate:
    def __init__(self, alpha_e=0.1, delta_age=0.0, delta_soc=0.0):
        self.alpha_e, self.delta_age, self.delta_soc = alpha_e, delta_age, delta_soc

    def certify(self, remaining_tasks, energy_model, rho, e_rem, policy):
        e_req_up = energy_model.upper_bound(remaining_tasks, rho, policy)
        e_req_up = inflate_aging(e_req_up, self.delta_age)
        e_safe, e_ret = energy_model.safe_reserve(), energy_model.return_reserve()
        e_low = e_rem - self.delta_soc
        ok = (e_req_up + e_safe + e_ret <= e_low)
        return MissionEndurance(ok, e_req_up, e_safe, e_ret,
                                alpha=self.alpha_e, support=energy_model.support)

    def can_afford(self, e_next, mec, e_rem):
        return e_next + mec.e_safe + mec.e_ret <= e_rem - self.delta_soc

    def must_return(self, mec, e_rem):
        return e_rem - self.delta_soc < mec.e_safe + mec.e_ret


# IP-381 EnergyLatencyParetoLadder：二维帕累托链
class EnergyLatencyParetoLadder:
    def __init__(self, students, wcet, energy, U_d):
        self.S, self.w, self.e, self.theta = students, wcet, energy, U_d

    def build(self):
        # 1) 先按 (w,e) 做帕累托裁剪，禁止被支配档
        keep = pareto_front([(i, self.w[i], self.e[i]) for i in range(len(self.S))])
        # 2) 并集门保证授权单调，资源取前缀最大值保证链序
        for rank, i in enumerate(keep[1:], start=1):
            j = keep[rank - 1]
            self.S[i] = UnionGate(self.S[i], self.S[j], (self.theta[j], self.theta[i]))
            self.w[i] = max(self.w[i], self.w[j])
            self.e[i] = max(self.e[i], self.e[j])
            assert self.acc(j) <= self.acc(i) <= self.acc_teacher()
        return self

    def acc(self, i):
        return {(x, a) for (x, a) in self.support
                if self.S[i].margin(x, a) >= self.theta[i]}

    def rung(self, i):
        return self.S[i], self.w[i], self.e[i], self.theta[i]


# IP-382 SustainabilityRouter：时间 + 能量 + 债务选档
class SustainabilityRouter:
    def __init__(self, ladder, rtic, plg, mec, teacher_aio):
        self.L, self.rtic, self.plg = ladder, rtic, plg
        self.mec, self.T = mec, teacher_aio

    def route(self, x, B_time, e_rem, rho, d_t):
        if not self.plg.env.contains(rho):
            return self.fallback(x, "power_envelope")      # 包络外：不赌
        if self.mec.must_return(self.mec.current, e_rem):
            return self.fallback(x, "return_reserve")       # 只返航/停靠
        if d_t > self.plg.D_debt:
            return self.fallback(x, "debt_cap")
        budget_t = B_time - self.rtic.B_safe
        budget_e = e_rem - self.mec.current.e_safe - self.mec.current.e_ret
        for i in reversed(range(len(self.L.S))):
            if (self.L.w[i] + d_t <= budget_t
                    and self.L.e[i] <= budget_e
                    and self.L.cert_valid(i)
                    and self.plg.condition(self.L.rtic(i), rho, d_t)):
                return self.L.rung(i)
        return self.fallback(x, "no_sustainable_rung")

    def fallback(self, x, reason):
        # P^sus：零学习安全回退 / 返航 / 停靠 / a_ask
        return self.safe_return_or_stop(x, reason)

    def account(self, e_frame, e_ref, rho, e_rem):
        d_next, status = self.plg.update_debt(e_frame, e_ref, self.d_t)
        if status != "ok":
            self.mode = "conserve"
            return self.fallback(None, status)
        self.d_t = d_next
        self.e_rem = e_rem - e_frame
        return self.mec.certify(self.remaining_tasks, self.energy_model,
                                rho, self.e_rem, self.policy)

## 4. 推导

**引理 122（功率条件化 anytime 的中断安全）** 若 `A` 满足 v13 定义 583 的可靠性、单调扩张与授权上界，且 `f_0` 只返回 `Fallback(x)⊆Exec_v13`，则对任意 `ρ∈P_env` 与任意中断档 `k`，`(Acc_k,c_k)` 有效且 `Acc_k⊆Exec_v13`；加入 `d_t` 只影响"能否按时跑到该档"，不影响该档的中断安全性。证明：v13 引理 113 的归纳不依赖 `w_k` 的具体数值；`d_t` 只进入截止期可行性检查。若 `w_k(ρ)+d_t` 超预算，路由器停在更早的 `k'≤k`，由归纳仍是 `Acc_{k'}⊆Exec_v13`。∎ 推论：**功率状态恶化与延迟债只会让系统停在更保守的档，而不会把早退变成不安全**。

**引理 123（延迟债的有界性与可偿还性）** 在定义 597 的更新下，若路由器强制 `d_t+κ(e_t−e_ref)_+≤D_debt`，则对所有 `t` 有 `0≤d_t≤D_debt`；若存在长度为 `T` 的区间使 `e_t≤e_ref` 且 `r_t≥r_min>0`，则 `d_{t+T}≤max(0,d_t−T·r_min)`；若低功率区间足够长，债务在有限步内归零。证明：由 `clip` 与路由器前置约束直接得上下界；偿还期内每步至少减 `r_min`，故至多 `⌈D_debt/r_min⌉` 步归零。∎ 推论：**"借来的实时"必须用低功率帧偿还；路由器不能用未来更便宜的空想做无限透支**。

**引理 124（MEC 的单侧覆盖）** 设能量残差 `z_i = E_req,i − Ê_req,i` 在校准/部署支撑内可交换，`Ê_req` 取加权共形上分位（含老化/温度膨胀），则
```
P( E_req(H) ≤ Ê_req ) ≥ 1−α_e−ε_shift−δ_age .
```
因此当 `Ê_req+E_safe+E_ret≤E_rem^low` 时，任务能量、安全储备与返回储备之和以至少 `1−α_e−ε_shift−δ_age` 的概率不超过剩余能量。证明：标准分裂共形 + 加权共形；老化膨胀项 `δ_age` 与温度模型误差作为保守加项；支撑外无保证，故 MEC 必须与 v13 UC 的支撑条件合取。∎ 推论：**续航的代价是活动性，不是安全性**；`Ê_req` 越保守，越早返航，但不会把"回不来"伪装成"还能跑"。

**引理 125（二维阶梯的嵌套安全与退化代价）** 对定义 599 的链 `(S_0,w_0,e_0)⪯_el…⪯_el(S_m,w_m,e_m)`，SR 取
```
i*(B_t,B_e,d)=max{ i : w_i+d≤B_t−B_safe, e_i≤B_e−E_safe−E_ret, RTIC_ρ,i 有效, MEC 有效 }。
```
则：(i) RTIC/MEC 有效时输出 `π_sus∈Exec_v13`；(ii) 期望授权价值关于 `B_t` 与 `B_e` 单调不减；(iii) 相对满档的期望退化满足
```
E[v_m−v(B_t,B_e)] ≤ Σ_{i=0}^{m-1} Δv_i · P( w_{i+1}+d>B_t−B_safe  ∨  e_{i+1}>B_e−E_safe−E_ret )。
```
证明：(i) 由链序 `Acc_i⊆Acc_T` 与 v13 引理 117/122；(ii) 由 `i*` 关于两个预算单调与链序；(iii) 对指标函数做伸缩求和 `v_m−v=Σ_{i=i*}^{m-1}(v_{i+1}−v_i)`，按"至少一个预算不足以上升到 i+1"的事件放缩，再用并集界。∎ 推论：**二维退化是连续的、可预算的**；只要 `(w_0,e_0)` 在 `(B_safe,E_safe+E_ret)` 内，最坏情况也落在零假设回退，不会出现"无档可跑"。

**引理 126（实时—续航—授权三难下界）** 存在功率状态序列、任务序列与电池模型，使任何策略若同时要求
```
P(latency+d ≤ D) ≥ 1−δ_t ,   P(E_req+E_safe+E_ret ≤ E_rem) ≥ 1−α_e ,
```
则其平均授权价值相对满档至少损失
```
Ω( (v_m−v_0) · (1 − (E_rem−E_safe−E_ret)/(E_peak·H)) ) ，
```
或必须把任务完成率降低 `Ω(δ_t+α_e+δ_age)`。证明思路：构造一个"低电量 + 高热 + 重载荷"的对抗功率序列，使满档推理的能量消耗超过可持续预算；任何试图维持满档的策略必然要么透支返回储备，要么在热节流后错过截止期。用伸缩求和与能量守恒把"减少高档使用"与"授权价值损失"联系起来；δ 项由共形/老化误差的并集界给出。∎ 推论：**"每帧实时 + 全程续航 + 满授权"不可能同时成立**；必须在档位、任务完成率与储备之间显式交换。

**引理 127（安全继承与不可绕过性）** `Exec_v14⊆Exec_v13⊆Exec_v12`。证明：定义 605 中 `a∈Acc_{i*}` 且 `Acc_{i*}⊆Acc_T⊆Exec_v13`（v13 引理 114/117）；PLG 只把 `RTIC` 的有效域缩小到 `P_env` 并加入 `d_t`；MEC 只增加 `E_req+E_safe+E_ret≤E_rem^low`；ELPL 只做链内并集/裁剪，不扩大授权；SR 只在上述交集内选档；`P^sus` 要求 `π_f∈Exec_v13`。故任一 v14 被执行动作属于 v13 执行集。∎ 因此 v13 引理 117/118/120 与 v12/v11 的安全继承在 v14 上继续成立。

**引理 128（中立元退化等价 v13）** 将定义 603 的四个中立元注入 PLG/MEC/ELPL/SR 端口，则功率状态固定标称包络、`d_t≡0`、无任务级能量证书、阶梯退化为一维时间 DDL、路由器退化为 v13 RTCR；主闭环调用序列与 v13 逐位一致，再沿 v13 链退回 v12/v11/v10/v9/v8/v7/v6。证明：逐端口代入定义 603，并用定义 595–606 的边界条件核对；四端口互不相交且中立元不改变 v13 任何证书检查。∎

**引理 129（预算与开销守恒 v14）** 新增在线成本上界：PLG 状态查询/包络判定 O(1) ≤0.05ms；MEC 在 1Hz/事件触发下摊销 ≤0.2ms；ELPL 选档 O(log m) ≤0.1ms；SR 联合判定 ≤0.05ms；延迟债更新 ≤0.01ms。总决策 p99 仍 ≤22ms、50Hz 保持；能量监测开销 ≤10mW（≤36J/h），相对 500Wh 级电池 ≤0.002%/h。离线 MEC 重校准/ELPL 构建/CPD 训练不在关键路径。证明：逐项代入复杂度表并做静态 EDF 校验 `ΣŴ_m≤B_dec`；能量监测为常数功耗。∎

**引理 130（低电量/热越界/债务越界下的安全塌缩）** 若 `ρ∉P_env` 或 `E_rem^low<E_safe+E_ret` 或 `d_t>D_debt`，SR 只允许 `P^sus` 中的零学习回退/返航/停靠/`a_ask`。则碰撞/越界等物理硬违规概率不高于 v13 对应回退；活动性损失满足
```
P(无可执行认证动作) ≤ P(ρ∉P_env) + P(MEC 失效) + P(P^sus 预算耗尽) + P(返航路径不可达) 。
```
证明：零学习回退由物理构造保证安全（停/柔顺/`a_ask`），且 `P^sus` 要求其在本帧截止期与能量预算内可完成；低电量/热越界时 ELPL 高档被 MEC 与 PLG 双重排除。∎ 推论：**低电量不是用更快的档位去赌，而是用最省电的档位去买返航时间**。

**引理 131（老化与温度误差下的 MEC 保守性）** 若电池容量衰减上界为 `δ_age`、温度模型误差上界为 `δ_T`，且 `Ê_req` 已按 `δ_age+δ_T` 膨胀，则 MEC 的单侧覆盖仍成立，仅活动性下降；若老化不可辨识或超出 `P_env`，MEC 只能退化为"立即返航/停靠"证书。证明：把老化/温度误差作为能量上界的单调加项，代入引理 124 的共形不等式；不可辨识时支撑条件被破坏，按定义 598(4) 只能回退。∎ 推论：**续航证书的失效模式必须是"更早返航"，不能是"继续跑直到没电"**。

## 8. 已知风险与失效模式

1. **能量模型与电池老化低估（最危险）**：MEC 的 `Ê_req` 在标称电池/常温下标定，低温内阻、容量衰减、重载地形会让真实能耗超出上界；路由器为守截止期不断花掉返回储备，最终"账面无误但回不来"。缓解：老化/温度膨胀项、周期容量标定、在线能量账本只升不降、`E_ret` 硬预留、低电量提前返航。
2. **延迟债模型的正反馈**：`κ` 若低估热膨胀，系统会认为借债很便宜，持续高档运行，直到热节流使所有档同时变慢。缓解：`κ` 取硬件在环上界、债务上限、温度越界强触发降档、禁止连续多帧借债。
3. **SoC/能量估计误差**：库仑计漂移、电压回弹、负载瞬态会让 `E_rem` 偏高。缓解：`δ_soc` 保守扣除、电压/电流联合估计、低电量区加密度采样、返航阈值留双倍余量。
4. **二维阶梯非链序**：独立蒸馏学生可能出现"授权更大但更耗能/更慢"的档，若强行部署，路由会跨档跳到不可持续学生。缓解：帕累托裁剪、并集门、资源前缀最大值、部署前 100% 链序校验，不满足即退化为 v13 一维阶梯。
5. **过度保守导致活动性塌缩**：MEC 在 60% 电量就要求返航，或 `E_safe+E_ret` 过大，使系统几乎不执行任务。缓解：分任务/地形校准储备、增加省电档、把"可充电"纳入任务规划、显式量化假返航代价。
6. **返航路径不可达/充电座被占**：MEC 假设返回路径可通行，实际被人/宠物/障碍阻断。缓解：多备选停靠点、返航前重新规划、把返航可达性纳入 `P^sus`、通信求助/`a_ask`。
7. **能量感知蒸馏削弱授权**：为省电把学生压得太小，边界余量变差、假拒绝升高，活动性下降。缓解：能量价格与假拒绝代价联合调参、保留教师 anytime 路径、关键场景禁用极省电档。
8. **四预算联合失效**：低电量、热节流、分布漂移与蒸馏间隙同时发生，`U_gap+U_dis` 与 `E_req` 同向低估。缓解：四预算加性、双重漂移检测、任一预算失效即 `a_ask`/最低档、联合三角界。

## 9. 本轮最大风险

**一句话**：MEC 的能量模型是在标称电池、常温与已知任务分布上校准的，而真实系统的电池老化、低温内阻上升、重载地形与热节流会让"剩余任务能量上界"被系统性低估；路由器为守住每一帧截止期不断花掉本应留给返回的能量，直到某一帧仍然按时、账面仍然平衡，却已经没有足够的电回到安全区——即**每帧都实时、每笔能量都记账、任务却回不来的"可持续性幻觉"**。
