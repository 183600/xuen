## 0. 本轮研究日志（2026-10-23，RUBICON 3.0 → 4.0 SCF → 4.1 PPSC-S）

> 说明：状态文件当前 best 是 RUBICON 3.0；候选 4.0 SCF 已经指出“接口对齐 + 状态覆盖”是更底层的瓶颈，但它需要额外硬件/采集，且没有直接回答三条灵感词。本轮把 SCF 的必要发现吸收为 P1，把主押注转为 **RUBICON 4.1 / PPSC-S**：不搭新采集台，先把现有 VLA 的关键帧验证、撤销修复和接触路径做到可落地。详细方案、公式、实验与来源在产物区。

### 0.1 我先做了什么

这轮没有先写方案，而是先做四件核实：

1. **重新抓官方页面**：主页、挑战页、排行榜、runs、详情页、Feishu 中英文手册、GitHub `unibot_submission`、HF collection 与数据集卡。
2. **看原始 HTML，不看渲染后的表**：确认排行榜仍是随机占位，而不是“已经公布但很低”。
3. **用 HF API 重新统计 32 个数据集**：episodes、frames、时长、相机、语言复述、gripper 约定。
4. **用 arXiv API 检索 2026 年最接近的工作**：MPC/test-time verification、latent world model、可解释谓词、TAMP、safety shield、failure attribution。

### 0.2 三个会改变方案的硬事实

#### 事实 A：公开榜仍是随机占位，29.7% 不是真实榜首

`leaderboard.html` 原始脚本仍写着：

> “The real, randomly-generated leaderboard is rendered here purely to sit (blurred) behind the ‘排行榜即将公开’ overlay. … this script only fills it in; it never unmasks anything.”

`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`。`runs.html` 与详情页也仍是“测试视频占位”。所以：

- **不能**说“MolmoAct2 以 29.7% 排第一”；这 8 行是随机生成。
- 用户简报里的“榜首不到 30%”与占位分布一致，但**只能当难度直觉，不能当证据**。
- 真实排名可能在登录后的私有榜单里；公开页面不可见。所有策略必须用本地 LPL/论文，而不是占位分数。

#### 事实 B：运行时接口比上一版假设的更窄

`unibot_submission` 的观测目录只有：

| 类别 | 运行时可用 |
|---|---|
| 图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`，480×640×3 |
| 本体 | 左/右臂 7+7、左/右 EE pose 6+6、左/右 gripper 1+1、`lower_body[15]` |
| 语言 | 单个 `str`，全 episode 不变 |

**没有** `depth` key、**没有** camera intrinsics/extrinsics、**没有** `state_torso`/`state_d435`/`waist_state_joint`。数据集里有这些额外状态和 `camera_params`（头部双目内参/畸变/R/T，`rectified: true`；腕部彩色内参），但评测端不发。因此：数据集标定可以当**离线先验**，运行时仍需自标定/相对几何，不能假设绝对 3D。

这直接推翻上一版“部件 3D centroid 默认来自深度”的路径。新方案必须满足：

- 用**相对视觉伺服 / 数据集标定先验 + 运行时自标定立体**，而不是假设绝对深度；
- 用**腕部近景**解决最后几毫米，而不是头部双目；
- 把数据集里的 `state_torso`/`state_d435` 只当**离线辅助监督**，不能当运行时输入。

#### 事实 C：数据规模与“长尾”是真实的

我用 HF API 统计了 32 个数据集：

- **33,276 episodes**，**18,282,246 frames**，30 fps 下 **169.28 h**；平均 episode **18.3 s**。
- 最长：ToolboxStorage **37.6 s**、StorePaddle **34.1 s**、SpellRobot **31.2 s**、PackPhone **29.2 s**、FoldTowel **25.8 s**。
- 每任务 **5 条英文复述**（`tasks.parquet`，`@` 分隔）。
- Dex1 gripper：**5.5 = open，0.0 = close**。
- 数据集卡 license 为 **apache-2.0**；GitHub 代码 repo 未发现 LICENSE（404/None）。两者要分开对待：数据可用，代码/模型权重仍需逐项确认。

这意味着：**长任务的状态维护、接触精度、撤销恢复**不是抽象问题，而是数据里真实存在的长尾；同时公开数据是**成功演示**，没有 failure/recovery/force 标签，评测却专门考这些状态。

### 0.3 文献给出的真正空位

我读了 2026 年最接近的几条线，按证据强度排序：

| 工作 | 证据 | 它做了什么 | 留给我们的空位 |
|---|---|---|---|
| **VeriVLA**（arXiv 2610.21985，2026-10-15） | 3 个真机任务 | flow VLA 的 test-time verification：两轴 trigger + JEPA latent world model 排序候选 chunk；完成分 50.8→65.5%，触发时 +326 ms | 验证目标是 latent progress，不是部件谓词；没有 undo/repair；同步开销大 |
| **Calibrated Predictive Safety**（arXiv 2608.17496，2026-08-18） | **仅 LIBERO-Long 仿真** | K 候选 + JEPA rollout + calibrated progress/risk + 确定性 safety shield | 最接近“MPC+安全”，但没有真机；没有部件级谓词；没有撤销修复 |
| **SITCOM**（arXiv 2510.04041，2025-10-05） | SIMPLER 仿真 | learned dynamics + reward-based rollout selection，48→72% | 说明 test-time compute 有效；依赖 reward/动力学；没有真机长尾 |
| **RePlanMem-VLA**（arXiv 2610.22556，2026-10-15） | 仿真 + 真机 replay | 连续 chunk 的 disagreement 作为事件检测，ROC-AUC 0.981–0.997 | 几乎零额外计算的 trigger 信号；但没有把它用于谓词修复 |
| **ConceptTree**（arXiv 2607.17861，2026-07-20） | 真机多任务 | 可解释 concept predicates 做 skill selection | 谓词只用于选技能，没有用于验证/撤销/修复 |
| **PDDL-ART**（arXiv 2608.17146，2026-08-17） | 真机维护/ household | 从单次演示自动生成 PDDL domain/problem | 适合离线建 plan schema；在线全量 TAMP 延迟/合规风险高 |
| **Multi-Link Safety**（arXiv 2609.40007，2026-09-30） | 仿真 6 种 hazard | 五椭球多连杆 shield，2.2 ms CPU | 用 RGB-D；运行时没有 depth；需要改用双目/学习深度 |
| **PaCo-VLA**（arXiv 2606.00515，2026-05-30） | 仿真 + 真机 connector | passivity shield + compliance prior | 运行时没有 force/torque，不能直接照搬 |
| **Think Like a World Model**（arXiv 2609.24682，2026-09-21） | LIBERO/RoboCasa | 把 world-model 表征蒸馏进 VLA，32 ms/1.86 GB | 比在线 14B world model 更适合本赛；可作为离线教师 |
| **DATAFARM**（arXiv 2609.12316，2026-09-11） | 3 个桌面任务 | TAMP 轨迹分布对齐后 56.7%，raw TAMP 只有 8.3% | 说明“仿真/TAMP 数据”不是免费午餐；只能当 P2 |

**空位总结**：现有工作分别解决了“test-time 验证”“latent 世界模型”“可解释谓词”“符号规划”“安全 shield”，但没有一条把它们组合成**面向官方撤销式干扰、单模型、低延迟、自部署 API** 的闭环。这个空位就是本轮的切入点。

### 0.4 三条灵感词到底落在哪

#### MPC：不做 30 Hz 连续 MPC，做 chunk 级“投机 MPC”

- 不做：30 Hz 力矩/阻抗 MPC。没有动力学模型、没有力觉、运行时不下发标定，且“单模型”定义有合规风险。
- 做：**关键状态下的 K 候选 action chunk 预测排序**。VLA 一次给出 H 步 chunk；在接触、撤销、低置信时，采样 2–4 个候选，用同一 checkpoint 的 latent dynamics 预测“谓词变化/成功率/风险”，选最优执行。
- 更进一步：**异步投机验证**。`get_action` 先返回 nominal chunk；后台在 chunk 执行期间验证；下一次调用若缓存新鲜就用排序结果，否则回退 nominal。这样 326 ms 的验证可以藏进 `T_chunk = H/f`，而不是加到每次调用上。

#### 可解释性：不做 post-hoc saliency，做“谓词即控制状态”

- 谓词不是解释给观众看的，而是**控制回路的一部分**：`grasped / in_hand / inserted / on_hook / closed / stacked / sorted / in_box / opened / aligned / human_near / stable`。
- 每个 action chunk 附一个 **certificate**：预期谓词变化、置信度、风险、预计时间。它用于：
  1. 选择/拒绝候选；
  2. 检测撤销（true→false）；
  3. 触发最小修复；
  4. 失败归因（perception/grasp/alignment/occlusion/timeout）；
  5. 安全门禁（人手接近、碰撞风险）。
- 这比“注意力热图”更可测试：谓词有 ground truth、有 AUC、有误报率。

#### 路径规划：不做全量 TAMP，做“谓词空间修复 + 接触路径”

- **谓词空间**：把技能写成前置/效果，A* 在 12 个谓词上找“从当前状态到目标”的最短修复路径；撤销后只重跑受影响子目标，不重跑全程。
- **几何空间**：为每个技能生成 approach/grasp/lift/transfer/place/retreat 的 EE waypoint；用 URDF + 胶囊近似做桌沿/自碰撞/人手检查；接触阶段切到腕部视觉伺服，小步 + backoff。
- **传送带**：T24 用常速模型预测拦截点；这是 MPC 思想最直接的单任务落点，但不是主战场。

### 0.5 本轮主押注：RUBICON 4.1 / PPSC-S

> **PPSC-S = Predictive Part-State Control with Speculative verification**：把 MPC 从关节/扭矩空间搬到**部件谓词空间**；只在关键帧对少量候选 chunk 做异步投机验证；撤销时用谓词图做最小修复。

它不是“再训一个更大的 VLA”，而是给现有 VLA 加三个接口：

1. **Part-State Observer（SPA-VLA 延续）**：16 个 part queries → 部件存在性、affordance、2D keypoint、descriptor、可选深度；所有头在同一个 checkpoint。
2. **Predicate Dynamics Verifier（PDV）**：动作条件 latent rollout，预测谓词 delta、成功率、风险；用反事实 chunk 排序训练；校准后用于 MPC 打分。
3. **Speculative MPC Scheduler（SMS）**：trigger + token bucket + 后台验证 + 缓存 + fallback；把额外计算藏进 chunk 执行时间。

配套：

- **RPSM 2.0**：谓词回退检测 + 最小修复；用 RePlanMem 式 chunk disagreement 作为免费 trigger。
- **FAC（Failure Attribution Certificate）**：证书 + 失败归因，服务调试与 portfolio。
- **CPP（Contact Path Planner）**：接触路径/视觉伺服；服务插头、网线、拉链、瓶盖、钥匙、针管。

### 0.6 组合与修剪

| 优先级 | 创新点 | 一句话 | 本轮动作 |
|---|---|---|---|
| P0 | **PPSC-S** | 部件谓词空间的异步投机 MPC | 主押注，先做离线排序 + 延迟仿真 |
| P0 | **RPSM 2.0** | 撤销检测 + 最小修复 | 用官方 8 条 undo 备注做测试集 |
| P0 | **FAC** | chunk 证书 + 失败归因 | 先做日志/诊断，不直接追分 |
| P0 | **CPP** | 接触路径 + 腕部视觉伺服 | 先在 T10/T26/T19/T14 做 |
| P1 | **IPT 接口对齐** | 训练/评测同分布；缺失键 dropout；动作掩码；EE 桥接 | 先做，避免离线指标骗人 |
| P1 | **标定先验 + 自标定立体** | 数据集 `camera_params` + proprio 自标定 | 先做离线可行性 |
| P1 | **LTCG** | N 端口/p99/热/显存的 test-time compute 预算 | 与 SMS 一起做 |
| P1 | **Portfolio + LPL** | 按成功率口径分配调试预算 | 保留，每周更新 |
| P2 | **World-model 表征蒸馏** | 离线教师，运行时单模型 | 作为 PPSC 的增强 |
| P2 | **TAMP 数据增广** | 分布对齐后再微调 | 时间不够则放弃 |
| P2 | **Human-aware shield** | 多连杆 + 单目/双目人手 | 安全兜底，不追分 |

**本轮修剪**：

- **全量连续 MPC**：没有动力学/力觉，延迟和合规都不划算；只保留 chunk 级 MPC。
- **Passivity shield**：运行时没有 force/torque，无法做能量罐；降级为位置式 compliance + backoff。
- **在线全量 PDDL/TAMP**：延迟高、任务特定风险高；只保留离线 schema + 运行时谓词修复。
- **14B world model 在线部署**：算力/延迟不划算；改为表征蒸馏。
- **在线 RL / 大规模仿真 RL**：样本效率、安全、时间都不允许。
- **任务特定硬编码轨迹**：违反泛化精神，可能违规；只用语言 + 谓词 + 通用技能图。
- **“再大一点的 VLA”**：不是本轮边际收益所在；本轮比的是状态接口、验证和恢复。

### 0.7 一句话押注

**把 MPC 缩到“部件谓词空间 + 异步投机验证”：只在接触/撤销/低置信的关键帧，用同一 checkpoint 的 latent dynamics 对 2–4 个候选 chunk 做预测排序，平时零额外延迟；再用可解释谓词做最小修复。它比再训一个更大的 VLA 更可能把 5 个 0–10% 的硬任务各抬 20pp，从而把总平均成功率抬过 30%。**

## A. 结论

本轮在候选 **4.0 SCF** 的接口/状态覆盖发现之上，升级为 **RUBICON 4.1 / PPSC-S**。4.0 SCF 的贡献是把“接口对齐 + 成功数据的状态覆盖不足”摆到台面上；但 SCF 需要额外硬件/采集，8 周内风险高，而且没有直接回答三条灵感词。4.1 吸收其接口对齐为 P1，把主押注放在现有 VLA 的关键帧验证、撤销修复和接触路径。核心不是“再训一个更大的 VLA”，而是把 **MPC 从关节/扭矩空间搬到部件谓词空间**，并把它做成一个**异步、可预算、可解释**的运行时层：

1. **PPSC-S（Predictive Part-State Control with Speculative verification）**：只在接触、撤销、低置信等关键帧，用同一 checkpoint 的 latent dynamics 对 2–4 个候选 action chunk 做预测排序；`get_action` 先返回 nominal chunk，后台在 chunk 执行期间验证，下一次调用用缓存结果。这样 test-time compute 不直接加到每次调用的 p99 上。
2. **RPSM 2.0（Reversible Part-State Memory）**：官方 `human_1/human_4` 大量是**撤销已完成子目标**（T10/T12/T14/T16/T17/T19/T24/T27）。RPSM 维护可逆的部件谓词 belief，检测 `true→false`，用谓词图做**最小修复**，而不是重跑全程。
3. **FAC（Failure Attribution Certificate）**：每个 chunk 附“预期谓词变化/置信度/风险/时间”的证书；失败后归因到 perception/grasp/alignment/occlusion/timeout，服务调试、portfolio 和安全门禁。
4. **CPP（Contact Path Planner）**：不做全量 TAMP；做接触感知的 EE waypoint + 腕部视觉伺服 + 小步/backoff，服务插头、网线、拉链、瓶盖、钥匙、针管。
5. **LTCG（Latency-aware Test-time Compute Governor）**：N 端口共享模型时的 token bucket、全局 semaphore、动态 batching、chunk padding、4h soak。

**最重要的口径修正**：公开榜的 29.7% 仍是**随机占位**，不是真实榜首；不能拿它做证据。官方排序是**总平均成功率优先，步骤分只是 tie-breaker**。32×10=320 次试验，p≈0.3 时总平均成功率的 SE≈2.56pp；1–2pp 的差距基本是噪声。策略应瞄准**0–10% 的长尾任务**，用 3–5pp 的真实增益而不是榜单波动。

**与上一版（3.0）的关键变化**：

| 3.0 | 4.1 | 原因 |
|---|---|---|
| 部件 3D centroid 默认来自深度 | 相对视觉伺服 + 数据集标定先验/自标定立体/学习深度 | 运行时没有 depth key、不下发 camera intrinsics；数据集有 `camera_params`，但运行时相机对应关系未明示，不能假设绝对 3D |
| RPSM 作为独立记忆模块 | RPSM 2.0 + RePlanMem 式 disagreement trigger + 最小修复 | 免费事件信号；把“记忆”变成“可执行修复” |
| 世界模型 P3 | 表征蒸馏 P2；在线只保留小 verifier head | 14B world model 在线不划算；VeriVLA/Think Like a World Model 证明蒸馏/小 verifier 更可行 |
| 未强调接口对齐/状态覆盖 | 吸收 4.0 SCF 的 IPT 为 P1；用反事实增广补 failure/recovery | 公开数据是成功演示；训练/评测键不一致会让离线指标骗人 |
| 部件感知接触伺服 | CPP：waypoint + 腕部视觉伺服 + backoff | 没有力觉；位置式 compliance 更稳 |
| Compliance Compiler | 保留，增加“单模型/辅助头”解释与 fallback | 规则未明示辅助头是否算第二模型 |
| Endurance Governor | LTCG：与异步验证绑定 | test-time compute 的 p99/并发是新的主要矛盾 |

以下所有事实以 **2026-10-23** 可访问的公开页面/文件为准；无法核实的地方明确标“未核实”。

## C. 竞争与瓶颈分析

### C.1 为什么成功率可能很低（假设，不是官方结论）

公开榜不可用，所以以下是**基于任务结构、接口约束和论文短板的假设**，需要用 LPL 验证：

1. **接触最后几毫米**：插头 prong、网线水晶头、钥匙、瓶盖、拉链、试管、针管。纯 RGB 端到端在头部视角只有厘米级；腕部近景 + 相对伺服才够。
2. **长程状态**：4–5 检查点任务（T09/T15/T16/T17/T18/T22/T28）容易漏点、premature stop、失败不重试。
3. **撤销式干扰**：官方 human 备注会撤销已完成子目标；单调进度头会把“毛巾被翻开”当成仍在“已叠好”阶段。
4. **未见物品/背景**：5 类泛化各 2 次；物体级 ID 过拟合会在换色/换形状时崩。
5. **部署稳定性**：4 路视频、N 端口、长时并发；p99/热/内存会直接吃掉成功率。
6. **数据覆盖**：33k episodes 看似多，但 32 任务平均 ~1k；长尾任务的失败模式覆盖不足。

### C.2 统计功效：为什么不要追 1–2pp

设任务 `i` 的第 `j` 次试验成功为 `y_ij ∈ {0,1}`，步骤分为 `q_ij ∈ [0,100]`：

```text
S = (1/32) * Σ_i (1/10) * Σ_j y_ij          # 总平均成功率
Q = (1/32) * Σ_i (1/10) * Σ_j q_ij          # 总平均步骤分
rank: S desc, then Q desc, then submission_date asc
```

总平均成功率的近似标准误：

```text
SE(S) ≈ sqrt( (1/32^2) * Σ_i p_i(1-p_i)/10 )
```

当所有 `p_i≈0.3`：

```text
SE(S) ≈ sqrt(0.3*0.7/320) ≈ 0.0256 = 2.56pp
95% CI ≈ ±5.0pp
```

**真实优势与“排名更高”的概率**（正态近似，320 次试验，两组独立）：

| 真实成功率优势 Δ | P(观测排名更高) |
|---:|---:|
| 0.5pp | 55.5% |
| 1.0pp | 60.8% |
| 1.5pp | 66.0% |
| 2.0pp | 70.8% |
| 2.5pp | 75.3% |
| 3.0pp | 79.3% |
| 4.0% | 86.1% |
| 5.0pp | 91.2% |

**含义**：

- 1–2pp 的榜单差距不能当真实优势；不要为它改架构。
- 想把“排名更高”的概率做到 ~80%，需要约 **3pp** 真实优势；~90% 需要约 **5pp**。
- 320 次试验下，检测 3pp 差异（80% power）需要约 3,700 次/组；本赛不可能靠增加 trials 解决，只能靠**更大的真实增益**和**降方差**。

**边际价值**：

```text
一个任务 +10pp  → 总平均 +0.10/32 = +0.31pp
一个任务 +30pp  → 总平均 +0.94pp
五个任务 +20pp  → 总平均 +3.1pp
五个 0%→30%     → 总平均 +4.7pp
全部 32 任务 +2pp → 总平均 +2.0pp
```

所以：**先消灭 0%，再在 3–5 个短板上各拿 20–30pp**，比在强任务上抠 1–2pp 更划算。

## D. RUBICON 4.1 架构

### D.1 一个 checkpoint，四个头

```text
4 views (high L/R, wrist L/R) + proprio + language
                    │
                    ▼
        VLA backbone (single checkpoint)
                    │
     ┌──────────────┼──────────────┬──────────────┐
     ▼              ▼              ▼              ▼
 Part head     Predicate head   Action head   Risk head
 (16 queries)   (12 predicates)  (chunk)       (collision/human)
     │              │              │              │
     └──────► Part-State Observer ◄┘              │
                    │                             │
                    ▼                             │
        Predicate Dynamics Verifier (PDV) ◄───────┘
                    │
                    ▼
        Speculative MPC Scheduler (SMS)
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
  Plan Repair (RPSM 2.0)   Contact Path Planner (CPP)
        │                       │
        └───────────┬───────────┘
                    ▼
          action chunk + certificate
```

**关键点**：

- 所有学习头共享 backbone；运行时**不加载 SAM3/PartSAM/世界模型**。
- `Part head`：16 个共享 part queries，输出存在性、affordance、2D keypoint、descriptor、可选深度；用 Hungarian matching 与离线教师对齐。
- `Predicate head`：12 个通用谓词的概率；时序用 GRU/HMM 平滑。
- `PDV`：动作条件 latent rollout，输入 `z_t + candidate chunk`，输出 `Δpredicate / success / risk`；可用 JEPA 式 frozen encoder + 小 transformer。
- `Risk head`：碰撞、人手接近、超时风险；校准后用于约束。
- `Action head`：底座原有的 flow/diffusion/AR 动作头；PPSC 只加 cross-attention/条件，不改动作空间。
- **Planner/Scheduler 是算法，不是第二个模型**；如果规则对“辅助头”有疑问，见 D.6 的 fallback。

### D.2 运行时循环（伪代码）

```python
def get_action(obs):
    z = encode(obs)
    parts, preds = part_head(z), predicate_head(z)

    # 1. belief update + regression detection
    belief = update_belief(prev_belief, preds)
    regressed = detect_regression(prev_belief, belief)

    # 2. nominal chunk (fast path)
    a_nom = action_head(z, noise=0)

    # 3. trigger
    trig = (disagreement(prev_chunk, a_nom) > tau_d) \
           or (min_conf(preds) < tau_c) \
           or in_contact_phase(preds) \
           or human_near(obs) \
           or regressed

    # 4. speculative verification (async; does not block this call)
    if trig and budget.available():
        candidates = [a_nom] + action_head.sample(z, K-1)
        submit_async(verify, z, candidates, belief)

    # 5. use cached ranking if fresh
    if cache.ready() and cache.fresh(z, belief):
        a = cache.best()
    else:
        a = a_nom

    # 6. plan repair on regression
    if regressed:
        a = repair_policy(belief, goal_predicates, certificate_cache)

    # 7. certificate + safety filter
    cert = make_certificate(z, a, belief)
    a = safety_filter(a, cert)
    return a
```

**注意**：

- `action_head.sample` 对 flow/diffusion 底座用不同噪声种子；对 AR 底座用 temperature/dropout/多 head。
- `cache.fresh` 检查观测是否发生大变化（part keypoint 位移、光学流、人手进入、谓词翻转）；不新鲜就回退 nominal。
- `repair_policy` 不直接输出电机指令，而是选择技能/子目标，再让 action head 生成 chunk；避免“规划器绕过 VLA”。

### D.3 异步投机 MPC：把 326ms 藏进 chunk

#### 时间线

```text
t0: get_action(obs_t)
    ├─ encode + part/predicate (fast)
    ├─ a_nom = action_head(z)
    ├─ return a_nom  ──────────────────────────► evaluator executes a_nom for T_chunk
    └─ submit_async verify(z, candidates)

t0 .. t0+T_chunk:
    verifier computes scores (K candidates)
    cache = ranking

t1: get_action(obs_{t+1})
    ├─ if cache.fresh and ready: a = cache.best()
    └─ else: a = a_nom
```

#### 延迟条件

```text
T_chunk = H / f
同步验证: T_call = T_policy + T_verify
异步验证: T_call ≈ T_policy
隐藏条件: T_verify + T_comm < T_chunk
```

| H（30Hz） | T_chunk | 同步 326ms 是否超预算 | 异步是否可藏 |
|---:|---:|---|---|
| 8 | 267ms | 是（p99 预算 ~213ms） | 否（326>267） |
| 12 | 400ms | 是（预算 ~320ms） | 勉强（需 T_verify<400ms） |
| 16 | 533ms | 否（预算 ~426ms） | 是 |
| 24 | 800ms | 否 | 是，余量大 |

**建议**：

- 首选 `H=16`，`T_chunk≈533ms`；验证目标 <300ms；p99 预算 426ms。
- 如果实际控制频率不是 30Hz，用 `T_chunk = H/f` 重算；不要假设。
- 如果 `T_chunk < T_verify`：用 **chunk padding**——返回 H 步，但后 H/2 步是保守/保持动作；这样即使下一次调用晚到，机器人不会跑远。
- N 端口共享 verifier：全局 semaphore（如 2 个并发）+ token bucket（如每端口每 2s 最多 1 次）+ 动态 batching；p99 超预算时降级为 nominal。
- 预算不是“越多越好”：每 episode 最多 `V_max`（建议 6–8 次）；优先 regression > contact > low confidence > disagreement。

#### 为什么异步可行

README 明确：evaluator 执行 chunk 的 index 0..T_a-1，直到再次调用 `get_action`。因此 chunk 执行期间有 `T_chunk` 的空闲窗口。我们在这个窗口里做验证，下一次调用用缓存。**这是接口工程上的关键机会**：大多数队伍会把 test-time compute 做成同步，p99 直接爆；异步投机可以把额外计算“免费”藏掉。

### D.4 谓词 belief 与最小修复

#### 12 个通用谓词

| 谓词 | 含义 | 观测来源 | 典型任务 |
|---|---|---|---|
| `grasped(part, hand)` | 夹爪夹住部件 | gripper 状态 + part keypoint 距离 | 全部抓取 |
| `in_hand(part, hand)` | 部件随手动 | 光流/相对位姿 | 全部 |
| `inserted(part, target)` | 插入到位 | 相对位姿 + 接触 | T10/T12/T26/T31 |
| `on_hook(cup, hook)` | 挂在钩上 | 相对位姿 | T01 |
| `closed(zipper/lid/case)` | 拉链/盖子/盒子闭合 | 部件 keypoint/边缘 | T09/T17/T18/T19/T31 |
| `stacked(obj, base, k)` | 堆叠第 k 层 | 相对位姿/高度 | T20/T25/T27 |
| `sorted(item, bin)` | 分拣到料盒 | item/bin 位置 | T04/T24 |
| `in_box(item, box)` | 放入盒/包 | 包含关系 | T03/T17/T18/T28/T29 |
| `opened(cap/zipper/case)` | 打开 | 部件状态 | T14/T17/T19/T31 |
| `aligned(part, target)` | 对齐 | keypoint 误差/姿态 | T10/T12/T19/T26/T32 |
| `human_near(hand)` | 人手接近 | 单目/双目人检测/光流 | human 干扰 |
| `stable(scene)` | 无掉落/碰撞 | 光流/位姿突变 | 全部 |

> 谓词不是每任务一组；任务差异由语言和观测决定。模型**不接收 task id**。

#### 谓词图与 A* 修复

```text
reach(part) ──► grasped(part) ──► in_hand(part)
                                      │
                    ┌─────────────────┼─────────────────┐
                    ▼                 ▼                 ▼
              aligned+inserted   aligned+on_hook   aligned+stacked
                    │                 │                 │
                    ▼                 ▼                 ▼
                 done(insert)     done(hang)       done(stack)
```

- 每个技能有前置/效果/成本（时间、风险、证书置信度）。
- 撤销时：`b_t[m]` 从高变低 → 把该子目标标记为 undone → 从当前 belief 重新 A* → 只执行受影响的最短修复序列。
- 如果目标物体消失：重扫描；找不到则**安全停止**，不幻觉继续。
- 修复顺序：先修被撤销的子目标，再继续后续；如果后续依赖被破坏，回退到最早受影响的谓词。

#### 撤销检测

```text
regressed(m) = 1[ b_t[m] < b_{t-1}[m] - δ_m ] and 1[ b_{t-1}[m] > θ_high ]
```

- 用迟滞（θ_high/θ_low）和 2 帧持续，避免单帧抖动。
- 结合 RePlanMem 式 chunk disagreement：`disagreement > τ_d` 作为“事件”先验；只有 disagreement + 谓词回退同时成立才触发修复，降低误报。
- 人手遮挡时保持 belief，不强行翻转；人离开后重观测/重投影。

#### 官方 undo 备注（直接测试集）

| ID | human_1 | human_4 | 修复要点 |
|---|---|---|---|
| T10 | 抓插头前进行移动 | 将插头拔起 | 重新对齐/插入 |
| T12 | 锁向左移动 | 中途把锁拿走 | 重扫描；找不到安全停止 |
| T14 | 拧开盖子之后拧动回来 | 把瓶子向左移动 | 重新拧盖/倒药 |
| T16 | 将叠完的毛巾翻开 | 将叠完的毛巾翻开 | 重新叠被翻开的层 |
| T17 | 荧光笔向后 | 笔盒合上之后手动打开 | 重新放笔/合盒 |
| T19 | 把包向左边移动 | 拉上拉链之后拉开 | 重新拉链 |
| T24 | 可乐快到了然后放回传送带起点 | 薯片快到了然后放回传送带起点 | 重新分拣该物品 |
| T27 | 把粉色碗向下移动 | 叠了第二个之后拿下第二个 | 重新叠第二个 |

> T31/T32 的 `generalization` 备注为空；需要按同类任务补测试。

### D.5 接触路径与视觉伺服

#### Waypoint 序列

```text
pre_grasp → grasp → lift → transfer → pre_place → place → retreat
```

- 每个 waypoint 由 part keypoint + affordance + gripper 姿态生成；用 URDF 做关节限位/自碰撞/桌沿检查。
- 没有绝对深度时，用**腕部图像误差**驱动最后几厘米：`e = keypoint_target - keypoint_current`；用小步 `Δx = K_p e`，限幅，逐步收敛。
- 接触阶段：降低步长/速度，检测“无进展”（keypoint 不变、gripper 闭合但物体未动）→ backoff 2–5mm → 重试。
- 没有力觉：用位置式 compliance + 小步 + 超时；不要假装有阻抗控制。

#### 双腕角色

- `holder` / `actor` 角色由谓词和语言决定；例如 T19 一手扶包、一手拉拉链；T32 一手持针管、一手拉活塞。
- 角色可以交换；用 `both_hold` / `handoff` 谓词管理死锁。
- 双腕相对位姿约束用 EE pose 检查；不满足时先调整 holder，再动 actor。

#### 传送带（T24）

- 用 part keypoint 跟踪 + 常速模型估计物品速度；预测拦截点 `p_int = p_t + v * Δt`。
- 如果错过，重新预测；不要追着传送带跑。
- 这是 MPC 思想最直接的单任务落点；但只影响 1/32，优先级低于通用接触/撤销。

### D.6 单模型合规与安全

**合规解释**：

- 一个 checkpoint 包含 backbone、part head、predicate head、PDV、risk head、action head；所有任务决策由同一计算图产生。
- 教师（SAM3/PartSAM/世界模型/立体深度）只在离线；运行时不加载。
- Planner/Scheduler 是确定性算法，不是学习模型；不按任务切换权重；不喂 task id。
- 如果规则把“辅助学习头”也算第二个模型：fallback 为**单 backbone + early-exit 头**（共享权重，不新增独立模型），或去掉 PDV，只保留谓词 monitor + 规则修复。
- 安全 monitor 用规则式几何/深度/光流，不参与任务决策；若必须用人检测器，明确标注为 safety monitor。

**安全壳**：

- 工作空间包围盒、最大 EE 速度、最大关节速度、waist/base 限幅、夹爪力上限（若可设）。
- 人手/人臂最小距离：低于阈值降速，低于停止距离暂停；人离开后重观测/继续。
- watchdog：推理超时、NaN、动作超限、端口断连 → 保持/安全退出。
- 审计：每 trial 记录时间、动作统计、延迟、安全事件、修复事件。

## E. 形式化与预算

### E.1 部件谓词 MPC

设：

- `b_t ∈ [0,1]^M`：M 个谓词的 belief；
- `z_t`：VLA 的 latent；
- `a_{t:t+H}`：候选 action chunk；
- `f_θ(z_t, a) → (b_{t+H}, \hat{y}, \hat{r})`：PDV 的预测。

目标：

```text
J(a) = - \hat{y}(a)
       + λ_r * \hat{r}(a)
       + λ_t * (H / f)
       + λ_d * || a - a_nom ||^2
```

约束：

```text
b_{t+H} ⊨ goal            (软约束，进入目标谓词)
\hat{r}(a) <= r_max       (风险上限)
a ∈ A_safe                (关节/工作空间/人手距离)
```

选择：

```text
a* = argmin_{a ∈ {a_nom, a_1..a_{K-1}}} J(a)
s.t. constraints
```

执行前 `H_e` 步（`H_e < H`），重新观测，重复。这是标准的 receding-horizon；只是状态是部件谓词，而不是关节/扭矩。

### E.2 Trigger 与预算

```text
trigger = 1[disagreement(prev_chunk, a_nom) > τ_d]
        or 1[min_m b_t[m] < τ_c]
        or 1[contact_phase]
        or 1[human_near]
        or 1[regressed]

budget:
  per-episode: V_episode <= V_max
  per-port: token bucket rate ρ
  global: semaphore G
  priority: regression > contact > low confidence > disagreement
```

**建议初值**（需在调试通道标定）：

- `V_max = 6–8`；`ρ = 1/2s`；`G = 2`（N=3 时）。
- `K = 2–4`；`τ_d` 用验证集上 90–95 分位；`τ_c = 0.3–0.4`。
- 如果 p99 超预算：先降 `K`，再降 `V_max`，再增大 `H`，最后才降分辨率。

### E.3 延迟与并发

```text
T_chunk = H / f
p99_target = 0.8 * T_chunk
E[overhead] = p_trigger * (K * T_verify + T_sample)
```

- 同步：`T_call = T_policy + K*T_verify`；p99 容易爆。
- 异步：`T_call ≈ T_policy`；验证在 `T_chunk` 内完成。
- 共享 GPU：`T_verify` 随并发上升；用 batching 和 semaphore；记录 p50/p95/p99/jitter。
- 4h soak：成功率漂移 <5pp、显存增长 <5%、无崩溃、热节流可降级。

### E.4 统计模型

对每个任务维护 Beta 后验：

```text
p_i ~ Beta(α_i, β_i)
α_i = α0 + k_i
β_i = β0 + (n_i - k_i)
```

- 先验：Easy `Beta(3,3)`、Medium `Beta(2,4)`、Hard `Beta(1.5,5)`；也可统一 `Beta(2,2)`。
- 目标：最大化 `E[S]`；接近目标时最大化 `P(S > S*)`；惩罚高方差任务。
- 选择下一个调试任务：`score_i = (target_i - E[p_i]) / cost_i`；对 `P(p_i < 0.05) > 0.5` 加“no-zero”优先级。
- `cost_i` 用历史调试时长、接触密度、任务时长、失败模式数估计；FAC 的失败归因可以更新 cost。

### E.5 预期增益场景

| 场景 | 计算 | 总平均增益 |
|---|---|---:|
| 5 个 0% → 30% | 5×0.30/32 | +4.7pp |
| 5 个 10% → 30% | 5×0.20/32 | +3.1pp |
| 3 个 0% → 25% | 3×0.25/32 | +2.3pp |
| 5 个 70% → 80% | 5×0.10/32 | +1.6pp |
| 全部 32 个 +2pp | 0.02 | +2.0pp |

> 结论：先修 0–10% 的长尾；PPSC-S 的目标不是“每个任务都涨”，而是“让 3–5 个系统性失败任务各涨 20–30pp”。

## F. 创新点清单（本轮迭代）

### F.1 P0-1：PPSC-S（主押注）

- **动机**：VLA 的 one-shot chunk 在接触/长程/撤销上容易不可逆失败；VeriVLA 证明 test-time verification 在 3 个真机任务上 +14.7pp，但同步 +326ms、只验证 latent progress、没有 undo。SITCOM 证明 MPC 式 rollout selection 在仿真 48→72%。
- **与现有方案差异**：验证目标是**部件谓词变化**，不是黑箱 progress；候选选择只在关键帧；**异步投机**把验证藏进 chunk 执行；同一 checkpoint，不跑第二个分割/世界模型；带 undo/repair。
- **技术可行性**：在现有 VLA 上加 part/predicate/PDV 三个头；PDV 可用 frozen backbone features + 小 transformer；K=2–4；H=16；离线反事实排序训练。VeriVLA 的 326ms 是 RTX4090 上的同步开销；我们的目标是蒸馏到 <300ms 并异步隐藏。
- **所需资源**：32 任务数据（33k episodes/169h）；8×A100/H100 微调 1–2 周；1×H100/L40S 推理；N 端口共享；无需 depth 传感器。
- **落地步骤**：① 部件/谓词标签；② 反事实 chunk 排序训练 PDV；③ 校准；④ 异步 scheduler；⑤ LPL A/B；⑥ 全 32 任务。
- **风险**：PDV 分布外、排序不准、缓存过期、并发 p99、单模型解释争议。
- **Kill**：E2 top-1 ranking <60% 或 pairwise <65%，或在线 A/B <1pp，则降级为“只保留 RPSM + CPP”。

### F.2 P0-2：RPSM 2.0（撤销修复）

- **动机**：官方 8 条 undo 备注直接撤销已完成子目标；单调进度头会继续做下一个子目标。
- **与现有方案差异**：不是“记住更多帧”，而是**可逆谓词 belief + 最小修复计划**；用 RePlanMem 式 disagreement 做免费 trigger；用谓词图 A* 只修复受影响子目标。
- **技术可行性**：12 个通用谓词；谓词头 + 迟滞；A* 在 CPU 上毫秒级；无需新模型；用官方备注构造测试集。
- **所需资源**：成功 episode + 合成 undo（反向播放/物体移除/状态翻转）；小算力；调试通道。
- **落地步骤**：① 谓词库；② 反向/移除/翻转增广；③ 修复 planner；④ 官方 8 任务测试；⑤ 集成到 PPSC。
- **风险**：谓词误报、遮挡、物体消失、修复顺序错误。
- **Kill**：undo detection AUC <0.8，或修复成功率 <50%，则退回“检测 + 安全停止”，不做修复。

### F.3 P0-3：FAC（证书与失败归因）

- **动机**：可解释性要服务调试/安全/portfolio，而不是 PPT；官方 score_steps 是天然 rubric。
- **与现有方案差异**：每个 chunk 的证书（预期谓词 delta/置信度/风险/时间）+ 失败归因（perception/grasp/alignment/occlusion/timeout）；不是 post-hoc saliency。
- **技术可行性**：复用 part/predicate/PDV 输出；日志格式简单；可用小规模人工标注验证。
- **所需资源**：日志、少量人工标签；无额外模型；无接口改动。
- **落地步骤**：① schema；② 记录；③ 归因规则/分类器；④ 与 LPL 结合；⑤ 审计。

- **Kill**：如果证书不能把调试时间降低 30%，降级为普通日志。

- **与现有方案差异**：token bucket + 全局 semaphore + 动态 batching + chunk padding + 降级阶梯；不是简单量化。
- **技术可行性**：纯工程；可测量；无需模型改动。
- **所需资源**：部署环境、监控、4h soak。
- **落地步骤**：① instrument；② 预算；③ 队列/batching；④ fallback；⑤ soak。
- **风险**：队头阻塞、热节流、显存泄漏。
- **Kill**：p99 超预算或 soak 漂移 >10pp，先修部署。

### F.7 P1-3：Portfolio + LPL

- **动机**：成功率优先；320 次试验；0% 任务边际收益最大；调试预算有限。
- **与现有方案差异**：Beta-Binomial + 边际收益/成本 + no-zero；用 FAC 失败归因更新 cost；不是平均用力。
- **技术可行性**：统计脚本；现有 LPL harness。
- **所需资源**：本地评测；日志；无额外模型。
- **落地步骤**：① 后验；② 分配；③ 复评；④ 停低弹性任务。
- **风险**：本地评测过拟合、噪声。
- **Kill**：连续两周无提升，转移预算。

### F.8 P2-1：World-model 表征蒸馏

- **动机**：world model 对物理泛化有用，但在线 14B 太慢；Think Like a World Model 证明表征蒸馏可在 32ms/1.86GB 部署。
- **与现有方案差异**：离线冻结教师 + 特征对齐；运行时单模型；不生成未来视频。
- **技术可行性**：需要合适教师；离线算力；一个对齐损失。
- **所需资源**：教师模型、GPU、数据。
- **落地步骤**：① 选教师；② 缓存特征；③ 蒸馏；④ 与 PPSC 联合评估。
- **风险**：教师域不匹配、增益小。
- **Kill**：<1pp，放弃。

### F.9 P2-2：TAMP 数据增广（分布对齐）

- **动机**：长程数据稀缺；TAMP 可生成轨迹，但 DATAFARM 显示 raw TAMP 只有 8.3%，对齐后 56.7%。
- **与现有方案差异**：只离线生成 + 分布对齐；运行时不用 planner。
- **技术可行性**：需要仿真/URDF/资产；时间长。
- **所需资源**：仿真、GPU、工程。
- **落地步骤**：① 建 sim；② 生成；③ 对齐；④ 微调；⑤ 评估。
- **风险**：sim2real、时间、资产。
- **Kill**：2 周内无 >2pp，放弃。

### F.10 P2-3：Human-aware shield

- **动机**：人为干扰就在工作区；碰撞可能终止评测/损坏机器人；README §6 关注交互质量。
- **与现有方案差异**：多连杆椭球 + 单目/双目人手检测 + 确定性过滤；不是第二个 policy。
- **技术可行性**：Multi-Link 2.2ms CPU；但需要 depth；用双目/学习深度替代。
- **所需资源**：人手检测、URDF、CPU。
- **落地步骤**：① 检测；② 拟合；③ 过滤；④ 红队。
- **风险**：误报、遮挡、过于保守。
- **Kill**：成功率损失 >2pp，放宽。

### F.10b P1-4：IPT（接口对齐，来自 4.0 SCF）

- **动机**：数据集键（`head_stereo_*`、`state_torso`、`state_d435`、`waist_state_joint`、`action.lower_body`/`base_command`/`waist_action_joint`）与评测键（`cam_*`、`lower_body[15]`、`pivot` + 双臂 + grippers）不一致；训练时若不做掩码/dropout，离线指标会骗人。
- **与现有方案差异**：不改模型结构，只改数据/训练/部署契约：缺失键 dropout、动作掩码、EE 相对→base 系绝对桥接、数据集 `camera_params` 先验；用 manifest 和单测锁住接口。
- **技术可行性**：纯工程；无需额外模型；可在 1 周内完成；与 PPSC-S 共用同一 checkpoint。
- **所需资源**：接口 manifest、数据管线、调试通道、单测。
- **落地步骤**：① 生成 key/action manifest；② 训练时随机丢弃运行时不可用的键；③ 只监督可下发动作槽；④ 加 EE 桥接；⑤ 用 `example_env.py` 做 shape/token/数值回归。
- **风险**：对调试通道过拟合、相机键对应关系不明、动作语义误判。
- **Kill**：离线 LPL 与调试通道成功率相关性 <0.7，先修接口再谈模型。

### F.10c P2-0：CSC（反事实状态覆盖，轻量版）

- **动机**：公开数据是成功演示；评测考 5 类泛化 + 撤销式干扰，失败/恢复/接触状态覆盖不足。4.0 SCF 的 OCB 采集台方向正确，但 8 周内搭硬件风险高。
- **与现有方案差异**：不搭新采集台；用现有数据做**离线反事实增广**：反向播放、物体移除/替换、状态翻转（开/合、插/拔、叠/翻）、遮挡、人手 overlay；再用谓词/证书筛选真实可执行的片段。
- **技术可行性**：现有 33k episodes + 简单几何/图像增广；无需新传感器；与 RPSM 的 undo 测试集共用。
- **所需资源**：数据管线、少量人工筛选、GPU。
- **落地步骤**：① 反向/状态翻转片段；② 物体移除/替换；③ 人手/遮挡 overlay；④ 训练；⑤ 在官方 8 个 undo 任务上评估。
- **风险**：增广不物理、标签噪声、sim2real 差距。
- **Kill**：<1pp 或 undo 修复无提升，放弃。

## G. 实验设计

### G.1 离线实验

| ID | 假设 | 数据/设置 | 指标 | 通过标准 | Kill |
|---|---|---|---|---|---|
| E1 | 谓词头能检测撤销 | 成功 episode 反向最后 2–5s；物体移除/状态翻转 | AUC、误报率、检测延迟 | AUC>0.85，FAR<10% | <0.8 |
| E2 | PDV 能排序真 chunk | 真 chunk 为正；时间偏移/缩放/噪声/左右交换/跨 episode 为负 | top-1、pairwise、ECE | top-1>60%，pairwise>65% | 低于标准 |
| E3 | disagreement 是免费事件信号 | 连续 chunk 重叠；阶段转换/接触作为事件 | ROC-AUC、trigger rate | AUC>0.8，trigger<10% | AUC<0.7 |
| E4 | 证书能归因失败 | 小规模人工标注失败片段 | 归因准确率、调试时间 | 准确率>70% | <50% |
| E5 | 谓词图修复有效 | 离散谓词模拟器/脚本化 undo | 修复成功率、时间、步数 | >70%，时间<全程 50% | <50% |

**E2 细节**：反事实负样本不要求物理执行；只用“与真实未来不一致”作为负标签。这是无仿真器的离线排序实验，成本低、信号强。正样本是真 chunk；负样本包括：

- 时间偏移 ±2/±4 帧；
- 动作缩放 0.8/1.2；
- 高斯噪声（σ=0.05/0.1）；
- 左右臂交换；
- 从同任务其他 episode 取 chunk；
- 从其他任务取 chunk。

如果 PDV 连“真 chunk vs 明显错 chunk”都排不对，在线验证不会有用。

### G.2 在线 LPL

- 32 任务 × 10 trials；5 类泛化各 2；固定协议；所有 trial 落日志。
- 分层：位置/干扰物/背景/未见物品/人为干扰；每类 2 次。
- 统计：每任务 Wilson 95% CI；总体 bootstrap CI；报告 `E[S]`、`P(S>S*)`、`Var(S)`。
- 对照：A0 基线；A1 +part；A2 +predicate；A3 +PDV（同步）；A4 +异步；A5 +repair；A6 +CPP；A7 +certificate。
- 真机优先任务：T01/T04/T10/T15/T16/T24/T30（覆盖抓取、分拣、接触、长程、撤销、传送带）。
- 每任务 5–10 trials 先做 A/B；显著后再全量。

### G.4 指标

- 主：full success（每任务/总体）、95% CI。
- 次：step score（tie-break）、检查点完成率、超时率。

- E2 不达标 → 放弃 PDV，保留 RPSM/CPP/Portfolio。

- 接触任务 <+10pp → CPP 降级为平滑/backoff。
