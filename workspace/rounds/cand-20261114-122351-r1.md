# 第 70 轮（承接第 69 轮「FLUID-RAS 交互消歧闭环」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「任务分解」×「双臂协作」）

> R69 给闭环装上了「眼、嘴、手」：不确定就去看、去问、去探，用 VoI 决定问谁；并把不确定性拆成 aleatoric 与 epistemic。但它仍是一个**独奏者**，且有两个未经检验的隐含假设，正好被本轮两个灵感击中：
> - **任务结构是给定的。** R69 的所有采样都在一个固定动作空间里；它问「选哪条轨迹」，却从不问「这个任务该不该这样拆、该由谁做、两个子任务能不能接上」。当对象是新的、可关节化的、或指令本身有歧义时，**最大的不确定性不在动作层，而在分解层**。
> - **保守是一个标量。** R69 的回退是 `λ_floor` 作用在单一动作流上；在双臂系统里「两臂一起慢下来」既不是安全的充分条件，也不是必要条件——它可能让夹持打滑，也可能让插入卡死。
>
> 本轮两个灵感正好补上两块缺失：
> - **任务分解**告诉我们：分解不是输入，而是一个**假设**（task-graph hypothesis），有自己的先验、可行性、置信与可消解性；错误分解的代价是结构性的，且不能靠「多采样几条轨迹」消除。
> - **双臂协作**告诉我们：两个子任务各自可行，不代表合起来可行；真正的安全是**接口的兼容性**（共享对象的闭链约束、力闭合、工作空间、时间窗），而不是每个臂各自的局部安全。
>
> 核心命题：**把「任务分解」提升为一等的不确定性对象，把「双臂协作」建模为假设-保证契约的组合，把「保守」从一个标量升级为一个按角色分配的向量，把 R69 的「谁去问」扩展为「哪个臂、在哪个分解假设下、问什么」。** 只在结构假设可认证、接口可组合、预算内可消解时才执行分解；否则退化为「最安全的可行分解」或 R69 的单臂保守。命名 **DUET-RAS**（Dual-arm Uncertainty-aware Epistemic Task-contract RAS：双臂、不确定性感知、认知任务契约的风险自适应闭环；DUET 亦取「二重奏」——两臂共读一份乐谱，但允许在不确定处重新协商乐谱）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证、还能问什么」，R70 问「**谁做什么、怎么合起来、出错时谁让谁**」——从独奏到二重奏，从提问到协商乐谱，从统一刹车到差动刹车。

## 0. 直觉与动机

**灵感 1（任务分解 → 分解是假设，不是给定输入）**
直觉：人类面对「把桌上的东西收拾好」不会先验地知道该用一只手还是两只手、先搬哪个、在哪里交接。分解本身是一个**离散假设**：`co-carry`（两臂共搬）、`hold-and-act`（一臂固定、一臂操作）、`handover`（交接）、`sequential`（顺序单臂）、`independent`（各自独立）。R69 的流策略只能在某个固定分解内采样连续动作；它无法表达「我连这个任务该怎么拆都不确定」。更关键的是，**结构不确定性不能靠多采样同一策略消除**：采 100 条轨迹仍然是同一个错误分解下的 100 条轨迹。要消解它，必须提出不同的图、检查可行性、并主动获取能区分它们的信息。这是本轮的第一块基石。

**灵感 2（双臂协作 → 可行性由接口决定，而不是由子任务各自决定）**
直觉：两个子任务各自都「能完成」，合起来却可能物理上不成立。左臂要把杯子递给右臂，右臂的预抓取位姿若与左臂的当前构型冲突，交接接口就不可行；两臂共同搬一个刚性托盘时，它们构成闭链，相对运动必须落在抓取约束的零空间里，否则会拧坏物体或触发大力。R69 的证书是**单臂证书**；双臂需要的是**组合证书**：每个子任务满足自己的 `Pre/Post/Inv`，且每条接口 `I_e` 满足工作空间、力闭合、时间窗、不确定性预算四项兼容条件。安全因此是**假设-保证（assume-guarantee）**的：一个子任务的保证必须能 discharge 另一个子任务的假设。接口不兼容时，再多的 λ 收紧也救不回来——这是本轮的第二个理论支点。

**灵感 3（对称保守是错的 → 保守必须按角色分配）**
直觉：R69 的回退是「任何不确定 → 都收紧」。在 hold-and-insert 里这是错的：左臂夹住方块需要**保持**足够的法向力 `f_h ≥ f_min`（否则打滑），右臂插入需要**降低**速度/刚度 `v_i ≤ v_max`（否则卡死或过力）。若两臂对称收紧（`λ_L=λ_R=λ`），λ 小则左臂夹不住，λ 大则右臂插不进；**不存在一个对称的 λ 同时安全**。正确的回退是**差分的**：左臂当 anchor（维持 `λ_L=1` 或更高刚度），右臂当 recovery（`λ_R<1` 慢退/慢插），或者反过来。更一般地，回退不是「两臂一起刹车」，而是「谁保持、谁退让、谁观察」的角色分配；当所有分配都不可行时，还有第三种比硬撑更安全的选择——**受控放置/顺从释放**（controlled stow）。这把 R69 的标量 `λ_floor` 升级为向量 `λ=(λ_L,λ_R)` 与角色映射。

**灵感 4（谁去问也是分解的一部分 → 交互动作需要跨臂认证）**
直觉：R69 选了「问什么」，但没选「谁来问」。在双臂系统里，信息动作会占用一个臂、扰动共享对象、遮挡另一个臂的视线；一个臂的探针可能就是另一个臂的扰动源。更微妙的是，两个臂的「一致回答」未必是两票：它们共享同一个基座、同一个对象、同一段历史，误差可能高度共模。所以「k 个正交证据源」必须**测量**而不是**假设**。CAM 因此把信息动作的选择从 `g` 扩展为 `(d, i, g)`：在哪个分解假设下、由哪个臂、执行什么信息动作；并同时满足跨臂认证（不能破坏另一臂的当前契约）与有效独立度 `κ_eff`（否则按一票计）。这把 R69 的「问对的人」升级为「派对的臂、问对的问题」。

**灵感 5（交接 = 承诺点 → 两阶段提交，可中止性优先）**
直觉：双臂协作最危险的瞬间是交接：物体从一只手换到另一只手，任何一方提前松手都会掉落，任何一方过晚松手都会拉扯。R69 的证据纪律在这里是必要的但不充分——「看到对方准备好了」不等于「对方真的能接住」。DUET 把交接建模为**两阶段提交**：Prepare（接收臂到位、张开、验证位姿/力/无滑移），Commit（双方就绪证书一致后才释放），Abort（保持臂不松手，接收臂退回）。安全由「提交前绝不释放」保证；活性由「最终就绪 + 公平调度」保证。若 readiness 长期不可验证，系统不应硬等，而应**重新分解**（例如改为「放到桌面再重抓」）——这正体现了「分解是假设」：交接失败不是动作失败，而是分解需要重选。

**灵感 6（结构投毒 → 分错比问错更危险）**
直觉：R69 的威胁模型是「回答可能撒谎」；DUET 多了一个更坏的攻击面：**分解可能被投毒**。人可以建议一个「看起来合理」但物理上不成立的分解（「你们俩各抓一端」——但那是一个铰接物体）；对象可能伪装刚性；两臂可能同时看到一个一致的假世界（共模欺骗）。结构错误的特点是**双臂相关**：R69 的错误动作只影响一个动作流，DUET 的错误分解会让两臂同步地、自信地执行一个不可组合的计划，误差在接口处放大。于是本轮必须交付：结构校准门（SCG）、接口兼容证书（ICC）、鲁棒分解证书（对歧义集取最坏情况）、以及「分解不可信时退回最安全可行分解」的纪律。

## 1. 形式化定义（增量：定义 310–327）

**定义 310（DUET-RAS 总览）** DUET-RAS = (TGP, FCC, HCC, HFP, SUD, CAM, AVA, HPC, RAS-WM‡)。五条不变式：
(i) **实时流零学习写操作**（继承 R69 定义 293-i）；
(ii) **组合安全**：被执行的分解决策 d 必须通过所有子任务契约与所有接口兼容证书 ICC；未认证的接口不得进入执行；
(iii) **保守分配**：回退是向量 λ=(λ_L,λ_R) 与角色映射 κ；anchor 臂的不变式优先于任务进度；任一臂的保守度不低于 R69 的 λ_floor(U_i)；
(iv) **证据纪律与物理独立**：单臂/单次回答不得单独定案；双臂证据只有测得有效独立度 κ_eff ≥ 2 时才按多源计，否则按单源计；
(v) **严格包含**：单臂、单子任务、无交接时，DUET 逐指令退化为 R69 FLUID-RAS。

**定义 311（分解假设与任务图）** 一个分解假设是类型化 DAG `G=(V,E,ρ,τ)`：V 为子任务节点；E 为 precedence/coupling 边；ρ: V→{L,R,LR} 为臂分配；τ: V→2^T 为时间窗。每个子任务 v 携带契约 C_v。分解空间 𝒢 = {G_j}，先验权重 w_j = p_φ(G_j|o)。

**定义 312（假设-保证契约）** `C_v = (Pre_v, Post_v, Inv_v, Res_v, U_v)`：前置条件、后置条件、执行中不变式、资源集、允许的不确定性预算。资源集 `Res_v = (W_v, F_v, T_v, O_v)` 分别为工作空间、力/力矩锥、时间窗、对象状态约束。子任务组合的接口 `I_{uv} = Res_u ∩ Res_v`（共享的工作空间、对象、时间、力通道）。

**定义 313（接口兼容证书 ICC）** 对边 e=(u,v)，`ICC_e = (W_ok, FC_ok, T_ok, U_ok)`：
- 共享对象时：两臂抓取矩阵满足力闭合，且相对运动位于抓取约束零空间（`G_rel ξ_rel = 0`）；不共享对象时：工作空间交叉部分存在认证无碰撞的协调策略；
- 时间窗重叠长度 ≥ 同步松弛 δ_sync；
- 接口不确定性预算 `U_u + U_v ≤ U_e^max`。
`ICC_e = true` 当且仅当四项全满足。若共享对象但力闭合不成立，则任何 λ 分配都无法使接口安全（引理 21）。

**定义 314（可认证分解）** `G` 可认证 iff 所有 `C_v` 在其假设下 valid 且所有 `ICC_e` 为 true。记 `J_comp(G) = ∧_v Valid(C_v) ∧ ∧_e ICC_e`。只有可认证的 G 才能进入 HFP 采样与执行。

**定义 315（双臂分层动作空间）** 低层动作 `ξ = (a_L, a_R, g_L, g_R) ∈ 𝒜_L × 𝒜_R`，其中 `a_i` 为任务动作、`g_i` 为该臂的信息动作（注视/探针/问句）。策略 `π_θ(ξ_{t:t+H} | o_t, d)` 以分解假设 d 为条件。R69 的单臂 `ξ=(a,g)` 是 `𝒜_R=∅` 的退化。

**定义 316（分层流策略 HFP）** 图嵌入 `e(d)`；速度场 `v_θ(x_s,s | o_t,d,z_t)`，`x_s=(1−s)x_0+s x_1`；`L_HFM = E‖v_θ − (x_1−x_0)‖²`。采样先 `d ~ p_φ(·|o)`，再对每个 d 采样 K 条双臂轨迹。图编码器轻量（≤1M 参数），trunk 与 R69 共享，零重复训练；`p_φ` 可由冻结 LLM/语法提出候选图，但**认证只由 FCC/HCC 做**，LLM 不获得认证权。

**定义 317（三层不确定性分解 SUD）** 
- `U_struct = H(D | o)`，D 只在**可认证图**上取支撑（不可行图被 mask，不参与熵）；
- `U_epi`：给定 d 后，R69 的动作模态歧义；
- `U_ale`：给定 d 与动作模态后的执行噪声。
三层语义不同，不做简单加和：`U_struct` 走「重分解/结构交互」通道，`U_epi` 走 R69 的交互通道，`U_ale` 直接进 λ floor。

**定义 318（风险加权结构 VoI）** 设 `d*(o)` 为当前最优可行分解，`R(d,o)` 为其组合风险（接口违反概率 × 后果 + 任务失败代价）。信息动作 g 的价值：
`VoI_R(g) = E_{y~p(·|g,o)}[ R(d*(o),o) − R(d*(o,y),o,y) ]`。
与 R69 的熵差不同，这里度量的是**决策风险**的下降：只有能改变分解选择或显著降低其风险的信息才值钱；两个风险相近的分解之间的「歧义」不值得问。选择 `g* = argmax_g [VoI_R(g) − c(g) − D_cross(g)]`，其中 `D_cross` 为对另一臂当前契约的扰动成本。

**定义 319（耦合感知 MINT / CAM：谁去问）** 联合选择 `(d, i, g)`，`i ∈ {L,R,both}`，满足：
- 交互预算与 R69 定义 293-ii；
- **跨臂认证**：`g` 由臂 i 执行时，必须同时通过臂 i 自身与另一臂当前契约的安全检查（不得破坏 anchor 的 Inv）；
- **共享工作空间互斥**：同一时刻至多一个信息动作占用共享对象/共享视域，除非两个动作被证明可并行且互不干扰；
- **有效独立度**：若两臂都提供证据，按 `κ_eff = 1 + (1−ρ_cm)·1[物理独立]` 计票，`κ_eff<2` 时不得宣称「两源一致」。
若 `max[VoI_R − c − D_cross] ≤ 0`：不交互，走 AVA 回退。

**定义 320（λ-向量与耦合安全集）** `λ=(λ_L,λ_R) ∈ [λ_min,1]^2`，`λ_i` 缩放臂 i 的速度/刚度/探索度（越大越保守）。耦合安全集
`S(λ) = { x : Inv_coupled(x, λ_L, λ_R) ∧ x ∈ 𝒳_safe }`，
其中 `Inv_coupled` 包含共享对象的力闭合、相对运动约束、碰撞与时间窗。R69 的标量回退是 `λ_L=λ_R=λ_floor` 的对角线；`S` 一般**不**关于对角线对称（引理 20）。

**定义 321（角色感知回退 AVA）** 角色 `κ ∈ {anchor, recovery, observer}`。回退求解
`(λ*,κ*) = argmax_{λ,κ} Progress(λ,κ)  s.t.  λ_i ≥ λ_floor(U_i) ∀i,  x ∈ S(λ),  κ 与 G 的耦合边一致`。
若可行集为空，进入**受控放置/顺从释放**（controlled stow）：把共享对象移到支撑面或按认证的顺从轨迹释放，再重新分解。R69 的单臂情形下，`κ` 退化，可行集与 R69 的 λ_floor 一致。

**定义 322（交接契约与两阶段提交 HPC）** 交接子任务 `v_ho` 的契约扩展为 `(Prepare, Commit, Abort)`：
- Prepare：接收臂到预抓取位姿、张开夹爪、验证 `R_ho`（相对位姿在容差内、夹爪孔径、力/力矩在界内、无滑移、时间窗未过期）；
- Commit：双方 `R_ho` 同时有效且提交截止期内，保持臂才释放；
- Abort：保持臂**绝不提前释放**，接收臂退回预抓取位姿。
安全：Abort 永远安全（保持臂未释放）。活性：在公平调度与最终就绪下，Commit 最终发生。

**定义 323（交接不确定性与替代分解）** `U_ho = P(¬R_ho | signals)`。交接不是必须的：若 `VoI_R` 表明「放置-重抓」或「单臂完成」的风险更低，则选择替代分解。这把 R69 的「问/不问」扩展为「交接/不交接/换一种拆法」。

**定义 324（结构投毒干扰集 ℰ_struct）** 包括：对抗性分解指令（「各抓一端」用于铰接对象）、欺骗性 affordance（看似刚性/轻质）、隐藏约束（易碎、液体、磁性）、幻觉任务图（模型提出场景不支持的分工）、跨臂共模欺骗（两臂同时看到一致的假世界）。并入 AIC：`ℰ_DUET = ℰ_FLUID^L × ℰ_FLUID^R × ℰ_struct`。

**定义 325（证书 J_DUET）** 
`J_DUET = (J_FLUID^L, J_FLUID^R, ECE_struct, ICC_all, U_struct_before, U_struct_after, λ_vector, role_map, handover_log_hash, robust_margin, duet_ver)`。
`Valid(J_DUET) ⇔ Valid(J_FLUID^L) ∧ Valid(J_FLUID^R) ∧ ECE_struct ≤ τ_s ∧ ICC_all ∧ λ* ∈ S(λ*) ∧ 证据纪律满足 ∧ 鲁棒裕度 ≥ 0`。

**定义 326（结构校准门 SCG）** `p_φ(G|o)` 需校准：可用性过滤（FCC）+ 可靠图 + ECE。`ECE_struct > τ_s` ⇒ 禁用结构 VoI，改用**最安全可行分解**（minimax over 𝒢_cert）；不可行图被硬 mask，而不是降权。SCG 是 R69 MCG 的结构层对应物，防止「分解幻觉」驱动双臂。

**定义 327（时序契约与同步松弛）** 对耦合边 e，`σ_e = |T_u ∩ T_v| − (dur_u + dur_v − overlap_required)`；若 `σ_e < δ_sync`，必须插入 wait/stabilize 子任务或重分解。交接的 Commit 有硬截止期 `t_commit`；超时即 Abort 并重分解。时序不是软约束，而是 ICC 的第四维。

```python
# IP-264 TGP：任务图提议（冻结 LLM/语法只提议，不认证）
class TaskGraphProposer:
    def propose(self, o, z, K_d=4):
        graphs = self.prior.sample(o, K_d)                 # co-carry / hold-act / handover / ...
        graphs = [g for g in graphs if self.fcc.feasible(g, o)]   # 硬可行性过滤
        return calibrate(graphs, self.ece)                  # 权重 + 校准

# IP-265/266 FCC+HCC：接口兼容证书与组合
def certify_graph(G, o):
    for v in G.V:
        if not contract_valid(G.C[v], o): return False
    for e in G.E:
        if not icc(G, e, o): return False   # workspace / force-closure / time / U-budget
    return True

# IP-267 HFP：图条件双臂流匹配（共享 R69 trunk）
class BimanualFlowPolicy:
    def sample(self, o, d, K, N_step=2):
        z, e = self.trunk(o), self.graph_enc(d)
        xs = randn(K, D_L + D_R)
        for i in range(N_step):
            xs = xs + (1.0 / N_step) * self.v(xs, i / N_step, z, e)
        return [self.decode(x) for x in xs]      # (a_L,a_R,g_L,g_R)

# IP-268 SUD：结构 / 动作 / 执行三层不确定性
def decompose_struct(graphs, w, samples, d):
    U_struct = entropy(w) * risk_gap(graphs)     # 只在可认证图上
    U_epi, modes = r69_decompose(samples)        # 复用 R69 AUD
    U_ale = sum(w_k * trace(cov(modes[k])) for k in modes)
    return U_struct, U_epi, U_ale, modes

# IP-269 CAM：谁去问（联合图 / 臂 / 信息动作）
def choose_joint_info(graphs, w, o, budget, other_contracts):
    best = None
    for d in graphs:
      for arm in (L, R):
        for g in info_actions(arm, d):
          if not budget.allow(g): continue
          if not c_ras_wm.certify_info(g, o, other_contracts): continue  # 跨臂认证
          if not mutually_exclusive(g, o): continue
          score = risk_weighted_voi(g, graphs, o) - cost(g) - cross_disturb(g, other_contracts)
          if best is None or score > best.score: best = (d, arm, g, score)
    return best if best and best.score > 0 else None

# IP-270 AVA：角色感知的 λ-向量分配
def allocate_lambda(U, G, roles):
    for role in consistent_roles(G):
        sol = solve(
            maximize progress(lam, role),
            subject_to=[lam[i] >= lam_floor(U[i]) for i in arms],
                       x in S(lam, G))
        if sol.feasible: return sol.lam, role
    return controlled_stow(G)                    # 认证的受控放置/释放

# IP-271 HPC：两阶段交接（提交前绝不释放）
def handover(holder, receiver):
    if not receiver.prepare(): return ABORT
    while not (receiver.ready_cert and holder.ready_cert):
        if now() > t_commit: return ABORT
        yield
    holder.release(); receiver.close()           # commit
    return COMMIT

# IP-276 主闭环（继承 R69，在结构层插入 DUET）
def DUET_RAS_round(M, obs):
    z, o = M.mtm.forward(...)
    graphs = M.tgp.propose(o, z)
    graphs = [g for g in graphs if certify_graph(g, o)]      # 组合过滤

    d = M.sud.select(graphs)                                 # risk-sensitive
    U_s, U_e, U_a, modes = M.sud.decompose_struct(...)
    # 结构歧义：允许问/探/换分解；谁去问也要跨臂认证
    g = M.cam.choose_joint_info(graphs, ..., o, M.budget, M.contracts)
    if g is not None: d = M.cam.update(...); U_s = M.cam.residual(...)
    # λ-向量回退（角色感知）；不可行则受控放置

    # 图条件双臂采样

    # 交接：两阶段提交；超时则重分解
    if has_handover(d) and not M.hpc.run(...): d = M.r69.redecompose(...)
    # 执行 + 审计 + 证书
    M.vqa_d.submit_async(d, graphs, g, lam, role)
    return d, lam, role, xi, (U_s, U_e, U_a)
```

## 3. 推导

**引理 19（结构信息增益与风险相关性）** 设两个可认证分解 d1,d2 的接口差异度为 Δ_IF（所需力闭合裕度/工作空间重叠/时间窗差），风险差为 Δ_R = |R(d1,o)−R(d2,o)|。执行信息动作 g 使结构后验熵降低 ΔH_s，则相较盲选，期望组合风险下降 ≥ c·Δ_R·(1−e^{−ΔH_s})；且当 Δ_R≈0 时，无论 ΔH_s 多大都无收益。系：**结构 VoI 是「风险相关的可分歧义」的函数，不是任务图数量的函数**；歧义大但风险等价时不应交互，应直接选最安全可行解。

**引理 20（对称保守的不充分性）** 考虑 hold-and-insert：左臂法向夹持力 `f_h = λ_L f_h^0`，右臂插入速度 `v_i = λ_R v_i^0`。安全要求 `f_h ≥ f_min`（不打滑）且 `v_i ≤ v_max`（不卡死/不过力）。当 `f_min/f_h^0 > v_max/v_i^0` 时：
- 若 `λ_L=λ_R=λ`，则 `λ < f_min/f_h^0` 时打滑；而 `λ ≥ f_min/f_h^0` 时必有 `λ > v_max/v_i^0`，插入速度越界；故**不存在对称安全 λ**；
- 取 `λ_L=1`（anchor 保持夹持）、`λ_R=v_max/v_i^0`（recovery 慢插），则两条件同时满足。
因此 R69 的标量回退在双臂耦合任务上可能**无可行的安全点**，而差动分配可行。系：保守不是标量，而是一个受角色约束的向量。

**引理 21（组合安全与接口不可修复性）** 若 G 的每条子任务契约在其假设下成立，且每条 ICC_e 成立，则并行组合满足所有 Inv 与安全约束（假设-保证放电）。反之，若某条接口的力闭合/时间窗/不确定性预算不成立，则不存在 λ 分配可使组合安全：接口约束是**状态可行性约束**，λ 只能缩放速度/刚度，不能改变抓取矩阵的秩或时间窗的交集。系：**先修接口，再谈保守**；接口不兼容时应重分解，而不是收紧。

**定理 18（DUET 严格包含 R69）** 在单臂、单子任务、无交接的边界上，`𝒢={G_0}`，ICC 为空真，λ 向量退化为标量，HPC 为空；DUET 的选择与 R69 逐指令相同。对一般双臂任务，DUET 的最优可行分解风险 ≤ 任何固定分解的 R69 风险；当结构 VoI ≤ 成本且无交接时，两者在动作层逐指令一致。因此 R69 是 DUET 在「无分解自由度」边界上的严格退化。

**定理 19（交接安全与活性）** 两阶段提交满足：(i) 安全性：保持臂在 Commit 前不释放，故 Abort 不掉落；(ii) 活性：在公平调度、最终 readiness 成立、且 `t_commit` 未超时的条件下，Commit 最终发生；(iii) 若 readiness 持续不可验证，超时 Abort 后重分解，系统回到可认证状态。系：交接的失败被转化为**分解的失败**，而不是物体的掉落。

**定理 20（结构投毒的鲁棒上界）** 设真实分解在歧义集 `𝒟_ε` 内，结构欺骗率为 δ_s，跨臂共模相关为 ρ_cm，有效独立证据数为 κ_eff。采用「对 𝒟_ε 取最坏情况的 ICC + κ_eff 证据纪律」时，错误分解被采纳的概率 ≤ `δ_s·ρ_cm^{κ_eff−1} + ε_ICC`；若 SCG 报 `ECE_struct > τ_s`，则退回 minimax 可行分解，其风险 ≤ `min_{d∈𝒢_cert} max_{d'∈𝒟_ε} R(d,d')`。系：**结构层的「问错」被转化为「分错」的上界**；当 ρ_cm→1（两臂完全共模）时，κ_eff→1，证据纪律退化为单源，系统必须选择 minimax 而不是「两票通过」。

## 6. 本轮最大风险

**一句话**：DUET-RAS 的全部收益押在「结构模型（分解提议 + 接口可行性）是可信的」这一前提上——**若它把不可组合的接口判成可组合，两臂会同步地、自信地执行一个物理上不成立的分解，误差在接口处共模放大；分错，比不问更危险。**

**次级风险与缓解**：
1. **结构校准失败/分解幻觉** → SCG 校准门 + 不可行图硬 mask + ECE 越界退 minimax；
2. **接口模型误差**（力闭合/时间窗/不确定性预算估错）→ ICC 不确定性预算 + 在线力/位残差监测 + 接口失败即重分解；
3. **对称保守的盲点** → AVA λ-向量 + 角色约束 + 受控放置兜底；
4. **交接活性与安全的张力** → 两阶段提交 + 超时 Abort + 不把交接当必须（允许「放置-重抓」替代分解）；
5. **结构投毒/跨臂共模** → 鲁棒 ICC（对歧义集取最坏）+ κ_eff 计票 + ℰ_struct 对抗训练；
6. **实时预算被 K_d/K 采样击穿** → K_d 门控 + 事件驱动 HPC + 共享 trunk；
7. **人类指令误解** → 冻结 LLM 只提议、不认证；FCC/HCC 物理认证 + E315 人类研究。

```python
def certify_graph(G, o):
    for v in G.V:
        if not contract_valid(G.C[v], o): return False
    for e in G.E:
        if not icc(G, e, o): return False   # workspace / force-closure / time / U-budget
    return True

# IP-267 HFP：图条件双臂流匹配（共享 R69 trunk）
class BimanualFlowPolicy:
    def sample(self, o, d, K, N_step=2):
        z, e = self.trunk(o), self.graph_enc(d)
        xs = randn(K, D_L + D_R)
        for i in range(N_step):
            xs = xs + (1.0 / N_step) * self.v(xs, i / N_step, z, e)
        return [self.decode(x) for x in xs]      # (a_L,a_R,g_L,g_R)

# IP-268 SUD：结构 / 动作 / 执行三层不确定性
def decompose_struct(graphs, w, samples, d):
    U_struct = entropy(w) * risk_gap(graphs)     # 只在可认证图上
    U_epi, modes = r69_decompose(samples)        # 复用 R69 AUD
    U_ale = sum(w_k * trace(cov(modes[k])) for k in modes)
    return U_struct, U_epi, U_ale, modes

# IP-269 CAM：谁去问（联合图 / 臂 / 信息动作）
def choose_joint_info(graphs, w, o, budget, other_contracts):
    best = None
    for d in graphs:
      for arm in (L, R):
        for g in info_actions(arm, d):
          if not budget.allow(g): continue
          if not c_ras_wm.certify_info(g, o, other_contracts): continue  # 跨臂认证
          if not mutually_exclusive(g, o): continue
          score = risk_weighted_voi(g, graphs, o) - cost(g) - cross_disturb(g, other_contracts)
          if best is None or score > best.score: best = (d, arm, g, score)
    return best if best and best.score > 0 else None

# IP-270 AVA：角色感知的 λ-向量分配
def allocate_lambda(U, G, roles):
    for role in consistent_roles(G):
        sol = solve(
            maximize progress(lam, role),
            subject_to=[lam[i] >= lam_floor(U[i]) for i in arms],
                       x in S(lam, G))
        if sol.feasible: return sol.lam, role
    return controlled_stow(G)                    # 认证的受控放置/释放

# IP-271 HPC：两阶段交接（提交前绝不释放）
def handover(holder, receiver):
    if not receiver.prepare(): return ABORT
    while not (receiver.ready_cert and holder.ready_cert):
        if now() > t_commit: return ABORT
        yield
    holder.release(); receiver.close()           # commit
    return COMMIT

# IP-276 主闭环（继承 R69，在结构层插入 DUET）
def DUET_RAS_round(M, obs):
    z, o = M.mtm.forward(...)
    graphs = M.tgp.propose(o, z)
    graphs = [g for g in graphs if certify_graph(g, o)]      # 组合过滤
    if not graphs: return M.r69.fallback(...)                # 无可认证分解
    d = M.sud.select(graphs)                                 # risk-sensitive
    U_s, U_e, U_a, modes = M.sud.decompose_struct(...)
    # 结构歧义：允许问/探/换分解；谁去问也要跨臂认证
    g = M.cam.choose_joint_info(graphs, ..., o, M.budget, M.contracts)
    if g is not None: d = M.cam.update(...); U_s = M.cam.residual(...)
    # λ-向量回退（角色感知）；不可行则受控放置
    lam, role = M.ava.allocate_lambda((U_a, U_e), d, roles=M.roles)
    # 图条件双臂采样
    xi = M.hfp.sample(o, d, K=1 if U_e < TAU_EPI else 4)
    # 交接：两阶段提交；超时则重分解
    if has_handover(d) and not M.hpc.run(...): d = M.r69.redecompose(...)
    # 执行 + 审计 + 证书
    M.vqa_d.submit_async(d, graphs, g, lam, role)
    return d, lam, role, xi, (U_s, U_e, U_a)
```

## 4. 推导

**引理 19（结构信息增益与风险相关性）** 设两个可认证分解 d1,d2 的接口差异度为 Δ_IF，风险差为 Δ_R。执行信息动作 g 使结构后验熵降低 ΔH_s，则相较盲选，期望组合风险下降 ≥ `c·Δ_R·(1−e^{−ΔH_s})`；当 Δ_R≈0 时无论 ΔH_s 多大都无收益。系：**结构 VoI 是「风险相关的可分歧义」的函数，不是任务图数量的函数**；歧义大但风险等价时应直接选最安全可行解。

**引理 20（对称保守的不充分性）** hold-and-insert 中 `f_h=λ_L f_h^0`、`v_i=λ_R v_i^0`，安全要求 `f_h≥f_min` 且 `v_i≤v_max`。当 `f_min/f_h^0 > v_max/v_i^0` 时，任何对称 `λ_L=λ_R=λ` 都不安全：`λ<f_min/f_h^0` 打滑，`λ≥f_min/f_h^0` 则 `λ>v_max/v_i^0` 使插入越界。取 `λ_L=1`（anchor）、`λ_R=v_max/v_i^0`（recovery）则同时满足。系：保守不是标量，而是受角色约束的向量。

**引理 21（组合安全与接口不可修复性）** 若所有子任务契约在其假设下成立且所有 ICC_e 成立，则并行组合满足 Inv 与安全约束（假设-保证放电）。反之，若某接口的力闭合/时间窗/不确定性预算不成立，则不存在 λ 分配可使组合安全：λ 只能缩放速度/刚度，不能改变抓取矩阵的秩或时间窗交集。系：**先修接口，再谈保守**。

**定理 18（DUET 严格包含 R69）** 单臂、单子任务、无交接时 `𝒢={G_0}`，ICC 空真，λ 退化为标量，HPC 为空，DUET 与 R69 逐指令相同。一般双臂任务中，DUET 的最优可行分解风险 ≤ 任何固定分解的 R69 风险；结构 VoI≤成本且无交接时动作层逐指令一致。R69 = 「无分解自由度」边界。

**定理 19（交接安全与活性）** (i) 保持臂在 Commit 前不释放 ⇒ Abort 不掉落；(ii) 公平调度 + 最终 readiness + 未超 `t_commit` ⇒ Commit 最终发生；(iii) readiness 持续不可验证 ⇒ 超时 Abort 后重分解，回到可认证状态。系：交接失败被转化为分解失败，而非物体掉落。

**定理 20（结构投毒的鲁棒上界）** 真实分解在歧义集 `𝒟_ε` 内、结构欺骗率 δ_s、跨臂共模相关 ρ_cm、有效独立证据数 κ_eff 时，错误分解采纳概率 ≤ `δ_s·ρ_cm^{κ_eff−1}+ε_ICC`；SCG 越界则退 minimax，风险 ≤ `min_{d∈𝒢_cert} max_{d'∈𝒟_ε} R(d,d')`。系：ρ_cm→1 时 κ_eff→1，证据纪律退化为单源，必须 minimax 而非「两票通过」。

## 7. 本轮最大风险

**一句话**：DUET-RAS 的全部收益押在「结构模型（分解提议 + 接口可行性）是可信的」这一前提上——**若它把不可组合的接口判成可组合，两臂会同步地、自信地执行一个物理上不成立的分解，误差在接口处共模放大；分错，比不问更危险。**

**次级风险与缓解**：结构校准失败/分解幻觉（SCG + 不可行图硬 mask + minimax）；接口模型误差（ICC 不确定性预算 + 在线力/位残差 + 重分解）；对称保守盲点（AVA λ-向量 + 角色约束 + 受控放置）；交接活性与安全张力（两阶段提交 + 超时 Abort + 允许「放置-重抓」替代）；结构投毒/跨臂共模（鲁棒 ICC + κ_eff + ℰ_struct 对抗训练）；实时预算（K_d 门控 + 事件驱动 HPC + 共享 trunk）；人类指令误解（冻结 LLM 只提议 + FCC/HCC 物理认证 + E315）。
