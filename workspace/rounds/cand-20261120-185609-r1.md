# 第 1 轮（新灵感循环；本轮灵感：「动作空间」×「可靠性」；基线 v16）

> **基线**：第 14 轮 MetricVoiceGauge-NCD-HUTDH-v16（定义 627–656；引理 131–136；实验 E671–E690）。
> 本轮纪律：**动作空间是变量、可靠性是货币、证书是汇率**。不推倒 v16：BTS/TRM/WBC/CSC/NCS/MCA/WCB（IP-402–408）、v15 的 SCD/DSD/DCA/EDC、v14 的 USG/TGC/BAA/GAGP/UC、v13 的 AIO/RTIC/CPD/DGC/DDL/RTCR、v12 的 USG/TGC、v11 的 HAS/HCC/HATD/HDT、v10 的 NGE/DSL/CC/CWM/CAE/NCP、v9 的 AC/MW/ID、v8 的 DA/SPR/Cal 与历轮不变式全部保留。四个新组件——CAS（证书化动作空间格）、RCM（可靠性证书监视器）、ARB（动作—可靠性预算分配器），以及支撑模块 RCC/CSA/RAA/RDS（复合演算、稀疏审计、可靠性感知抽象、漂移哨兵）——一律以**中立元**接入；任一失效即严格退回 v16（引理 144），再沿 v16→v15→…→v6 退化链退回。本轮只做三件事：把「动作空间」改写为**可证收缩的嵌套格**、把「可靠性」改写为**风险可加且任意时刻有效的证书**、把「动作空间 × 可靠性」改写为**数据—体积—可靠性三角约束下的单调收缩调度**。

## 0. 直觉与动机

**灵感 1（动作空间 → 可证收缩的嵌套格，而不是固定的背景集合）**
直觉：v16 的每个 NC 都把 `ActionSpace` 当成一个**给定的、不可讨论的**背景集合；可靠性只问"这个动作是否在证书内"，却从不问"我们凭什么是这个动作空间"。真机上动作空间本身是设计变量：力矩饱和、速度上限、任务空间授权、夹爪开合幅度、甚至可用执行器集合，都可以随时收紧；而每多开放一个维度或一个动作单元，就多欠一份"我会覆盖它"的证明债。于是真正的问题不是"在动作空间里选动作"，而是"**当前证据能支撑多大的动作空间**"。核心创新：**证书化动作空间格（Certified Action Space, CAS）**。把动作空间写成嵌套格 `A_0 ⊆ A_1 ⊆ … ⊆ A_L = A`，每一层 `A_ℓ` 携带体积 `V_ℓ`、单元划分 `Π_ℓ`、证书边界 `Cert(A_ℓ)` 与覆盖成本。运行时**只能沿格向下收缩**（降层或删单元），任何向上扩张都必须先完成与 v16"正向跃迁补课"同构的再验证。关键反直觉点：**更大的动作空间不代表更强的能力，只代表更大的证明承诺**——在固定证据预算下，开放更多动作反而降低可证可靠性；"能力"应被度量成"在要求可靠性下的已认证体积"，而不是原始动作空间的测度。

**灵感 2（可靠性 → 风险可加、任意时刻有效的证书，而不是跑完后的成功率）**
直觉：工程上最爱说"每一步 99.9%，所以一万步还接近 99.9%"——这是把可靠性当概率**连乘**。连乘只在步骤失效近似独立时成立；而机器人失效恰恰高度相关：同一块电池衰减、同一组关节过热、同一个接触模型失配，会同时抬高整条路径的失效风险（公共模式失效）。更隐蔽的是，串行任务的失效事件是**并集**，不是乘积；对任意相关性，并集只能给出风险相加（union bound），不能给出概率相乘。并且，机器人在线连续运行，可靠性不是一次实验结论，而是**随时可被审计**的量；用固定样本置信区间反复看，会在可选停止下系统性假阳。核心创新：**可靠性证书监视器（Reliability Certificate Monitor, RCM）**：对每个动作单元维护一个 e-process（证据过程），用 Ville 不等式反演出**任意时刻有效**的违例率上界 `p_up(c)`，再取 `r_c = 1 - p_up(c)`；路径可靠性用**风险缺口可加**复合 `ε_path = ⊕ ε_i = Σ ε_i`，`r_path ≥ 1 - ε_path`。关键反直觉点：**可靠性不能乘，只能加风险**——乘法是乐观的独立性幻觉，加法才是对任意相关失效都成立的保守下界；而稀疏到不足 `n_min` 的单元必须直接置 `r_c = 0`，任何"插值/平滑出来的高可靠性"都是把未知伪装成已知。

**灵感 3（动作空间 × 可靠性 → 数据—体积—可靠性三角与视界反比律）**
直觉：把前两者放在一起，会得到一个近乎守恒的约束。要在体积为 `V` 的动作空间上把单次调用缺口压到 `ε`，单元越多、每单元样本越少，Hoeffding 加并集界给出所需样本随 `V log V / ε²` 增长。于是"大动作空间 + 高可靠性 + 小数据"三者不可兼得：固定数据预算下，要更高可靠性就必须收缩动作空间；固定动作空间下，要更高可靠性就必须更多数据。更反直觉的是**任务视界**：若整个任务只允许缺口预算 `ε_budget`，串行 `T` 次调用下每次的缺口预算只能是 `ε_budget / T`；于是**任务越长，可证动作空间越小**——长时运行不是"更努力地跑"，而是"更收敛地授权"。核心创新：**动作—可靠性预算分配器（Action–Reliability Budget, ARB）**。它把调度改成"在可靠性下限 `r_req` 与数据预算 `N` 下，选择最高可证层 `ℓ*` 与可证单元子集 `S*`，最大化已认证体积 `V_cert(ℓ,S)`"，并维护影子价格 `λ_rel`（每单位认证体积消耗的可靠性缺口）。关键反直觉点：**可靠性是一种会被动作空间消耗的预算，而不是动作空间的属性**；正确的调度不是"先选动作再看安不安全"，而是"先算能买得起多大动作空间，再在里面选动作"。

**三者如何统一**
统一为 **v16 行为层之上的动作—可靠性授权层**：v16 回答"当前里程碑/模型阶层下能安全执行哪个全身行为"（`Exec_v16`），v17 回答"为了以不低于 `r_req` 的可靠性完成这个行为，允许开放多大的动作空间、能够证到哪一层、能维持多久"（`Exec_v17`）。CAS 把固定 `ActionSpace` 抬升为可收缩格；RCM 把"成功率"抬升为随时间一致有效的可靠性证书；ARB 用三角预算把 `(ℓ*, S*, r_req, N, T)` 锁成一个可行域；RAA 在可靠性下降时只做单调收缩；RDS 检测磨损/分布漂移并触发重校准；CSA 把稀疏单元钉死在零可靠性；RCC 定义路径上的风险可加复合。共享状态 `ζ_rel = (ℓ*, S*, r_path, ε_budget, T, N_cell, λ_rel, drift_rel, mode_rel)`。**CAS 回答"能开放多大"，RCM 回答"现在到底多可靠"，ARB 回答"买得起哪一层"，RAA/RDS 回答"什么时候必须收"，RCC 回答"整条路径的可靠性怎么算"**。六者不是六个补丁，而是"授权—证据—预算—收缩—监测—复合"的可靠性链，且 `Exec_v17 ⊆ Exec_v16`。

## 1. 研究问题（轮次升级版）

- **Q1（动作空间格的证书语义与收缩/扩张）**：如何为 `A_ℓ` 定义 `Cert(A_ℓ)`，使"层间嵌套"与"按单元删减"都保持可证单调？在安全集非凸（接触模式、摩擦锥、关节限位）时，单元划分 `Π_ℓ` 如何选才不把可行域切成不可证的碎片？向上扩张的"补课"需要多少独立证据，能否借用相似单元的迁移先验而不引入乐观偏差？
- **Q2（可靠性的任意时刻有效性与相关失效）**：如何为每个动作单元构造在非平稳、罕见违例下仍有功效的 e-process？Ville 反演得到的 `p_up(c)` 在连续监控、漂移重启、多层次同时检验下如何做 α-spending 而不失效？风险可加（union bound）在 `T` 很大时极保守，是否存在既依赖稳健又比裸并集更紧的复合（例如按 e-value 合并、分数预算）？公共模式失效如何显式入账而不是被并集"平均掉"？
- **Q3（数据—体积—可靠性三角与调度最优性）**：三角界 `N ≥ M log M / (2 ε_tick²)` 的常数与经验标度 `β` 如何校准？当单元样本非均匀、可主动采样时，ARB 如何在"采哪些单元"与"开放哪些单元"之间联合优化？`(ℓ*, S*, m*, h*, c)` 五维预算下的帕累托前沿如何刻画？影子价格 `λ_rel` 能否在线估计并用于跨里程碑分配可靠性预算？
- **Q4（退化、活性与正跃迁）**：CAS/RCM/ARB/RCC/CSA/RAA/RDS 任一失效时如何严格退回 v16？可靠性约束是否会把系统逼进"只剩 `A_0`、安全但不可动"的冻结死锁？如何区分"合理的保守"与"证据饥饿导致的永久停滞"？维护/换件带来的**可靠性正向跃迁**为何不能直接扩张动作空间，其补课延迟如何界定？端到端是否满足 `Exec_v17⊆Exec_v16⊆Exec_v15`？

## 2. 设计原则（在 P25–P27 基础上新增 P28–P30）

**P28 动作空间即可证收缩格律（Certified Contracting Lattice）**
动作空间必须写成嵌套格 `A_0 ⊆ A_1 ⊆ … ⊆ A_L = A`，每层 `A_ℓ` 携带 `(V_ℓ, Π_ℓ, Cert(A_ℓ), cost_ℓ)`。在线只允许**单调收缩**：`ℓ ← ℓ' ≤ ℓ` 或 `S ← S' ⊆ S`；任何扩张 `(ℓ↑, S↑)` 都必须先经过**补课算子** `Reverify`，即在新单元上取得 `n_min` 个独立样本（或给出有界分布距离的迁移修正），补课完成前旧授权 `ℓ*` 保持不变。收缩后的证书必须是原证书在子空间上的限制：`Cert(A_{ℓ'}) ⊇ Cert(A_ℓ) ∩ A_{ℓ'}`，从而"收缩不产生新的未证动作"。

**P29 可靠性即风险可加且任意时刻有效律（Reliability as Additive, Anytime-Valid Hazard）**
动作单元 `c` 的可靠性证书为 `RC_c = (r_c, T, α_rel, n_c, expiry)`，其中 `r_c = 1 - p_up(c)`，`p_up(c)` 由 e-process 在**任意停止时刻**有效的置信序列反演得到，`n_c < n_min ⇒ r_c = 0`。路径可靠性只能按**风险缺口可加**复合：`r_path ≥ 1 - Σ_i (1 - r_i)`，禁止默认使用 `Π_i r_i`（除非额外证明步骤失效独立且同分布，且即便那样也仅作诊断、不作安全授权）。任务视界内的缺口预算必须显式分配：`ε_tick = ε_budget / T`，每一次额外调用都在消耗同一份预算。

**P30 动作—数据—可靠性三角预算律（Action–Data–Reliability Triangle）**
对固定置信水平与单元划分，可靠性缺口、可证体积与样本量必须满足方向性约束 `N ≳ V_ℓ · log M_ℓ / (2 ε_tick²)`（常数与 log 因子由经验标度 `β_ℓ` 校准）。调度器必须在 `(ℓ*, S*, r_req, N, T)` 上联合求解：最大化已认证体积 `V_cert`，约束为每个被选单元 `p_up(c) ≤ ε_budget / T`、层号 `ℓ ≤ ℓ_allowed(m*, h*)`、样本 `n_c` 已结算。**不得用提高 `r_req` 的表态来替代收缩动作空间**：两者在三角中是可互换的预算，必须由影子价格 `λ_rel` 显式定价。

## 3. 与基线的接口（如何退化）

- CAS 失效 ⇒ 动作空间固定为 `A_L`、`ℓ*≡L`，CAS 退化为恒等映射，**等价 v16** 的固定 `ActionSpace`；
- RCM 失效 ⇒ 无可靠性证据约束 `r_c≡1`、`r_path≡1`，仅保留 v16 NC 的物理证书，**等价 v16**；
- ARB 失效 ⇒ 不做三角预算，开放全空间，**等价 v16** 的 `val(n)` 调度；
- RAA/RDS/CSA/RCC 失效 ⇒ 不收缩、不监测、不审计、用保守并集或退回 v16 CDS 步证书，**等价 v16（+CAS/RCM/ARB）路径**；
- 全部失效 ⇒ MetricVoiceGauge-NCD-HUTDH-v16，再沿 `v16→v15→v14→…→v6` 退化链退回；
- **安全继承**：CAS 只做子空间限制，RCM 只增加合取约束（可靠性下界），ARB 只做可行域筛选，RAA 只收缩，RDS 只触发重校准，CSA 只把单元可靠性置零。六端口均不能新增授权、放宽阈值或扩张动作空间；`Exec_v17⊆Exec_v16` 由引理 144 保证。

## 4. 预期贡献

1. **证书化动作空间**：把"动作空间"从固定背景改写为可证收缩的嵌套格，给出层间嵌套、单元删减与补课扩张的单调性条件，填补"动作空间大小与可证性脱节"的空白；
2. **任意时刻有效的可靠性证书**：用 e-process/Ville 把可靠性从一次性成功率升级为连续可审计的证书，并用风险可加复合正确处理公共模式失效，纠正"每步相乘"的系统性乐观；
3. **动作—数据—可靠性三角**：给出体积、样本、缺口之间的方向性预算界与视界反比律，说明"长任务必须缩小可证动作空间"，把可靠性变成可分配、可定价的预算；
4. **可靠性感知的单调收缩调度**：ARB 在 `(ℓ*, S*, m*, h*)` 上联合求解，RAA/RDS 只做向下收缩，CSA 拒绝稀疏单元，形成"能证多大就开多大"的在线授权链；
5. **语义—证据—授权—执行四层分离**：v12 管允许什么，v13 管时限内实现多少，v15 管技能扩散，v16 管全身行为，v17 管**动作授权与可靠性结算**，用 `Exec_v17⊆Exec_v16⊆Exec_v15⊆Exec_v13⊆Exec_v12` 把安全、可靠性、实时与行为全解耦；E691–E710 覆盖格单调、风险加法、任意时刻有效性、三角标度、视界反比、ARB 最优性、漂移与正跃迁、端到端与消融。

## 5. 本轮最大风险

**一句话**：可靠性证书只由机器人**实际采取过**的动作样本估计，而"采取过哪些动作"又由当前策略与当前授权决定——未被探索的动作单元永远是稀疏的、被置零的，于是 RCM 测到的其实是**策略的惯性**而不是**动作空间的可靠性**；一旦系统用这种自采样本去"证明"某个新单元安全，再借维护/换件造成的可靠性正向跃迁扩张授权，就会在"证据充分、任意时刻有效、风险可加"的表象下执行一个**从未被真正测量过、却因选择偏差而被认证为可靠的动作空间**——即**自我确认的可靠性幻觉**。

## 0. 定义与符号（定义 657–686）

| 符号 | 含义 |
|---|---|
| A | 原始动作空间（力矩/速度/位置/任务空间指令全集） |
| L(A) = (A_0,…,A_L) | 证书化动作空间格，`A_0 ⊆ A_1 ⊆ … ⊆ A_L = A`，`A_0` 为急停/柔顺最小授权 |
| V_ℓ = μ(A_ℓ) | 动作空间体积（Lebesgue 测度或单元测度之和） |
| Π_ℓ = {c_1,…,c_{M_ℓ}} | `A_ℓ` 的动作单元划分，粒度 `Δ_ℓ = V_ℓ/M_ℓ` |
| c ∈ Π_ℓ | 动作单元（cell），是可靠性统计与证书的最小单位 |
| R(π,T) | 策略 π 在任务视界 T 内零证书违规的可靠性 |
| p_c | 单元 c 的单次调用违例率 |
| n_c | 单元 c 的已结算样本数 |
| n_min | 单元最小可证样本数（默认 30，可按 EVT 调整） |
| r_c = 1 − p_up(c) | 单元可靠性下界；`n_c<n_min ⇒ r_c=0` |
| E_t(c;ε_0) | 单元 c 关于零假设 `p_c≤ε_0` 的 e-process（`E_0=1`） |
| α_rel | 可靠性证书族错误率（连续监控 + 多单元 + 漂移重启总预算） |
| RC_c = (r_c,T,α_rel,n_c,expiry) | 单元可靠性证书 |
| ε_budget | 整个任务视界允许的总可靠性缺口 |
| ε_tick = ε_budget/T | 单次调用缺口预算（由并集界分配） |
| ε_path = ⊕_i ε_i = Σ_i ε_i | 风险可加复合（union bound），对任意相关结构成立 |
| r_path ≥ 1 − ε_path；r_set = min_{c∈S} r_c | 路径可靠性下界（串行可加）；授权集可靠性（最差单元） |

# IP-416 Certified Action Space：证书化动作空间格
class CertifiedActionSpace:
    def __init__(self, levels, partitions, measures, cert_bounds):
        self.levels = levels            # [A_0, ..., A_L]
        self.partitions = partitions    # {l: frozenset(cells)}
        self.measures = measures        # {l: {cell: mu(cell)}}
        self.cert = cert_bounds         # {l: Cert(A_l)}
        self.l_max = len(levels) - 1

    def volume(self, l, S=None):
        cells = self.partitions[l] if S is None else S
        return sum(self.measures[l][c] for c in cells)

    def cells(self, l):
        return self.partitions[l]

    def contract_level(self, l, l_new):
        if l_new > l:
            raise ValueError("CAS only contracts online; expansion via reverify()")
        return l_new

    def contract_cells(self, S, drop):
        return frozenset(S) - frozenset(drop)

    def restricted_cert(self, l, S):
        # 收缩后的证书必须是原证书在子空间上的限制
        return self.cert[l].restrict(S)

    def reverify(self, l_target, S_add, audit):
        """扩张唯一入口：待新增单元必须各自达到 n_min 个独立样本"""
        for c in S_add:
            if audit.n_cells.get(c, 0) < audit.n_min:
                return None            # 补课未完成，拒绝扩张
            if not audit.independent(c):
                return None            # 自采样本非独立，拒绝
        return frozenset(S_add)

    def emergency_action(self):
        return self.levels[0].emergency_action   # A_0 心跳单元


# IP-417 Reliability Certificate Monitor：任意时刻有效的可靠性证书
import math

class ReliabilityCertificateMonitor:
    def __init__(self, alpha_rel=0.05, n_min=30):
        self.alpha = alpha_rel
        self.n_min = n_min
        self.n = {}          # cell -> 已结算样本数
        self.viol = {}       # cell -> 违例数
        self.ledger = {}     # cell -> 违例/成功序列（供 e-process 复核）
        self.epoch = {}      # cell -> 漂移重启后的 α-spending epoch

    def update(self, cell, violated):
        self.n[cell] = self.n.get(cell, 0) + 1
        self.viol[cell] = self.viol.get(cell, 0) + int(violated)
        self.ledger.setdefault(cell, []).append(int(violated))

    def alpha_epoch(self, cell):
        # 每次漂移重启消耗一半剩余预算，保证总族错误率仍 ≤ alpha_rel
        k = self.epoch.get(cell, 0)
        return self.alpha / (2 ** (k + 1))

    def p_upper(self, cell):
        n_c = self.n.get(cell, 0)
        if n_c < self.n_min:
            return 1.0                     # 稀疏 -> r=0（fail-safe）
        p_hat = self.viol.get(cell, 0) / n_c
        a = self.alpha_epoch(cell)
        # 时间一致 Hoeffding 置信序列（Ville + 混合界），任意停止时刻有效
        rad = math.sqrt(
            (math.log(math.log(max(n_c, 3))) + 0.72 * math.log(10.4 / a)) / n_c
        )
        return min(1.0, p_hat + rad)

    def r_lower(self, cell):
        return 1.0 - self.p_upper(cell)

    def path_lower(self, cells):
        # 串行路径：风险可加（union bound），禁止连乘
        if not cells:
            return 0.0
        gaps = [1.0 - self.r_lower(c) for c in cells]
        return max(0.0, 1.0 - math.fsum(gaps))

    def set_lower(self, cells):
        # 授权集合：只需保证"无论选中哪个单元"都达标，取最差单元
        if not cells:
            return 0.0
        return min(self.r_lower(c) for c in cells)

    def restart_epoch(self, cell):
        self.epoch[cell] = self.epoch.get(cell, 0) + 1
        self.n[cell] = 0                 # 旧样本不跨漂移复用
        self.viol[cell] = 0
        self.ledger[cell] = []


# IP-418 Action–Reliability Budget：三角预算下的授权选择
class ActionPlan:
    def __init__(self, l, S, V, r_set, eps_tick):
        self.l, self.S, self.V = l, S, V
        self.r_set, self.eps_tick = r_set, eps_tick
        self.score = V * max(r_set, 0.0)


class ActionReliabilityBudget:
    def __init__(self, cas, rcm):
        self.cas = cas
        self.rcm = rcm

    def solve(self, T, eps_budget, l_allowed):
        eps_tick = eps_budget / max(T, 1)
        best = None
        # 从高授权层向下尝试；不可行则单调收缩
        for l in range(l_allowed, -1, -1):
            eligible = [c for c in self.cas.cells(l)
                        if self.rcm.p_upper(c) <= eps_tick]
            if not eligible:
                continue
            V = self.cas.volume(l, eligible)
            r_set = self.rcm.set_lower(eligible)   # 最差单元，而非串行求和
            score = V * max(r_set, 0.0)
            plan = ActionPlan(l=l, S=frozenset(eligible), V=V,
                              r_set=r_set, eps_tick=eps_tick)
            if best is None or score > best.score:
                best = plan
        return best

    def shadow_price(self, plan):
        # λ_rel = 每单位认证体积消耗的缺口预算
        return plan.eps_tick / max(plan.V, 1e-12)


# IP-419 Reliability Composition Calculus：风险可加复合
class ReliabilityCompositionCalculus:
    def compose(self, node_type, child_gaps, common_mode=0.0):
        if node_type == 'Action':
            return min(1.0, child_gaps[0] + common_mode)
        if node_type in ('Sequence', 'Parallel'):
            return min(1.0, sum(child_gaps) + common_mode)
        if node_type == 'Selector':
            # 只执行一个分支：取被选分支的缺口；探测失败分支另计
            return min(1.0, min(child_gaps) + common_mode)
        if node_type == 'Decorator':
            # 只能收紧：缺口不小于子节点中最小者
            return min(1.0, min(child_gaps) + common_mode)
        raise ValueError(node_type)

    def path_budget(self, T, eps_budget):
        return eps_budget / max(T, 1)     # 视界反比律：长期任务单次预算更小


# IP-420 Cell Sparsity Auditor：稀疏审计
class CellSparsityAuditor:
    def __init__(self, n_min=30):
        self.n_min = n_min
        self.counts = {}          # cell -> 已结算样本数
        self.episode_seen = set() # (episode, cell) 去重

    def observe(self, cell, episode_id):
        self.counts[cell] = self.counts.get(cell, 0) + 1
        self.episode_seen.add((episode_id, cell))

    def audit(self, cells):
        sparse = frozenset(c for c in cells if self.counts.get(c, 0) < self.n_min)
        covered = frozenset(c for c in cells if c not in sparse)
        loss = len(sparse) / max(len(cells), 1)
        return sparse, covered, loss

    def independent(self, cell):
        # 至少 n_min 个不同 episode 的样本才算独立补课
        eps = {e for (e, c) in self.episode_seen if c == cell}
        return len(eps) >= self.n_min


# IP-421 Reliability-Aware Abstraction：可靠性感知的单调收缩
class ReliabilityAwareAbstraction:
    def __init__(self, cas, rcm):
        self.cas = cas
        self.rcm = rcm

    def contract(self, l, S, r_req):
        if self.rcm.set_lower(S) >= r_req:
            return l, S
        S = frozenset(S)
        # 1) 先删可靠性最差的单元
        order = sorted(S, key=lambda c: self.rcm.r_lower(c), reverse=True)
        for c in order:
            S = S - {c}
            if S and self.rcm.set_lower(S) >= r_req:
                return l, S
        # 2) 仍不满足则降层，并在新层重新筛单元
        for l2 in range(l - 1, -1, -1):
            elig = frozenset(c for c in self.cas.cells(l2)
                             if self.rcm.r_lower(c) >= r_req)
            if elig and self.rcm.set_lower(elig) >= r_req:
                return l2, elig
        return 0, frozenset()             # 只剩 A_0 急停/柔顺


# IP-422 Reliability Drift Sentinel：漂移哨兵
class ReliabilityDriftSentinel:
    def __init__(self, expected_gap=1e-3, threshold=5.0, drift_share=0.01):
        self.expected = expected_gap
        self.threshold = threshold
        self.share = drift_share
        self.cusum = {}

    def update(self, cell, violated, share=None):
        share = self.share if share is None else share
        s = self.cusum.get(cell, 0.0)
        s = max(0.0, s + int(violated) - self.expected - share)
        self.cusum[cell] = s
        return s > self.threshold

    def on_drift(self, cell, rcm, cas, l_star):
        rcm.restart_epoch(cell)
        self.cusum[cell] = 0.0
        return max(0, l_star - 1)          # 强制降一层，绝不上调

## 2. 推导（引理 137–144）

**引理 137（CAS 收缩的可证单调性）** 设 `ℓ'≤ℓ`、`S'⊆S⊆Π_ℓ`，且 `A_{ℓ'}` 的单元由 `A_ℓ` 的单元细分或限制得到，`Cert(A_{ℓ'})` 定义为 `Cert(A_ℓ)` 在 `A_{ℓ'}` 上的限制。则 `r_set(S') ≥ r_set(S)` 且收缩不引入新的未证动作：`Cert(A_{ℓ'},S') ⊇ Cert(A_ℓ,S) ∩ A_{ℓ'}`。证明：`p_up(c)` 只依赖单元 `c` 的样本，与所选集合无关；`r_set` 取所选单元可靠性最小值，删单元不会降低最小值，降层只会减少候选单元。证书限制的定义直接给出包含关系。∎ 推论：**收缩永远安全，问题只在于收缩是否过多**。

**引理 138（风险可加复合的依赖稳健性）** 设事件 `Ev_i` 满足 `P(Ev_i)≤ε_i`，允许任意相关结构。则 `P(∪_i Ev_i) ≤ Σ_i ε_i`，故 `r_path ≥ 1 − Σ_i (1−r_i)`。反之，默认的乘法复合 `Π_i r_i` 在一般相关结构下既不保证上界也不保证下界：当失效互斥时 `∪` 的真实概率可达 `Σ ε_i`，可严格大于 `1−Π_i(1−ε_i)`（例：两步各 `ε=0.1`，相乘给出缺口 `0.19`，互斥时真实缺口 `0.20`），乘法**低估风险**；当公共模式使失效完全同现时，乘法又高估风险。证明：并集界是概率测度的次可加性，与相关性无关；乘法等价于假设独立。∎ 推论：**可靠性只能沿路径"加风险"，不能"乘概率"**；公共模式缺口作为独立项 `ε_common` 计入 `Σ`，绝不被平均掉。

**引理 139（可靠性监视的任意时刻有效性）** 设 `p_up(t)` 为引理/算法中的时间一致置信序列，满足对真实 `p_c`，`P(∃t≥1: p_c > p_up(t)) ≤ α_rel`。则连续监控、随机停止、反复查看都不会使族错误率超过 `α_rel`；RDS 的每次重启按 `α/2^k` 做 α-spending 后，跨 epoch 的总错误率仍 ≤ `α_rel`。而固定样本置信区间在可选停止下失效：若每观测一步就检查，直到区间排除 `p_c` 为止，则排除概率随步数趋于 1，即使 `p_c` 从未改变。证明：时间一致界由 Ville 不等式对混合 e-process 得到；固定样本界没有对停止时刻取上确界，故其覆盖概率不成立。∎ 推论：**"随时可看的可靠性"必须用 anytime-valid 证书，"跑完再统计"的区间不能拿来在线授权**。

**引理 140（数据—体积—可靠性三角）** 设 `A_ℓ` 划分为 `M_ℓ` 个单元，样本总量 `N`，单元样本近似均匀 `n_c≈N/M_ℓ`，置信水平 `α`，单次调用缺口目标 `ε_tick`。由 Hoeffding 与对 `M_ℓ` 个单元的并集界，`ε_tick ≥ sqrt(M_ℓ(log M_ℓ + log(1/α))/(2N))`，等价地 `N ≥ M_ℓ(log M_ℓ + log(1/α))/(2 ε_tick²)`。证明：每单元 Hoeffding 尾概率 `≤ exp(−2n_c t²)`；并集 `≤ M_ℓ exp(−2n_c t²)`；令其 ≤ α，代入 `n_c=N/M_ℓ` 并解出 `t`。∎ 推论：**三角界是方向性约束而非紧常数**，常数、log 因子与有限样本效应由 `β_ℓ` 经验校准（E695）；它说明"大动作空间 + 高可靠性 + 小数据"三者不可同时满足。

**推论 140.1（可靠性—视界反比律）** 若任务总缺口预算为 `ε_budget`、视界内共 `T` 次调用，则 `ε_tick=ε_budget/T`，代入三角得 `N ≥ M_ℓ(log M_ℓ+log(1/α))T²/(2 ε_budget²)`。固定 `N` 与 `ε_budget` 时，可证单元数 `M_ℓ` 随 `T` 增大而单调减小；`T→∞` 时任何固定体积的动作空间都无法给出正的可靠性下界。证明：直接由 `ε_tick=ε_budget/T` 与三角单调性。∎ 推论：**长任务必须缩小可证动作空间**；"跑得越久越收敛"不是策略偏好，而是可靠性预算的数学后果。

**引理 141（ARB 的帕累托最优性与单调收缩）** 固定 `(T,ε_budget)`，对每层 `ℓ`，可行单元集为 `S_ℓ(ε_tick)={c∈Π_ℓ: p_up(c)≤ε_tick}`。则：(1) 在该层，`S_ℓ(ε_tick)` 是体积最大的可行子集（任何额外单元只会增大体积）；(2) 在全层上取 `max_ℓ V_cert(ℓ,S_ℓ)` 得到体积最优授权；(3) 当 `T` 增大或 `ε_budget` 减小时，`ε_tick` 减小，`S_ℓ` 与 `ℓ*` 单调不增，形成单向下调的授权轨迹。证明：(1) 约束逐单元独立，全部满足者组成的集合是唯一极大可行集；(2) 层枚举穷尽；(3) 阈值单调性。∎ 推论：**授权选择的"最优性"是逐单元阈值 + 层枚举，不需要 NP-hard 搜索**；真正的难点在证据的获取，而不是组合优化。

**引理 142（稀疏置零的安全性与活性损失界）** 令 `n_c<n_min ⇒ r_c=0`，则任何稀疏单元都不会被 ARB/RAA 选中，因而不会放行未测动作；活性损失满足 `P(无可认证动作) ≤ P(A_0 心跳单元 n<n_min) + P(r_set<r_req)`。由于 `A_0` 的心跳/急停单元在每个控制周期都被执行（即便任务动作全被拒），其样本以控制频率累积，故第一项随时间指数衰减。证明：稀疏单元可靠性为零，不能满足 `r_req>0`；心跳单元的采样过程与任务授权无关。∎ 推论：**"安全但不可动"的死锁只能来自心跳单元证据不足，而心跳单元天然有数据**；真正的冻结风险来自 `r_req` 被设得高于当前证据能买的水平。

**引理 143（v17 严格退化到 v16）** 取 `ℓ*=L`、`S*=Π_L`、`r_req=0`、`r_c≡1`、`n_min=0`、关闭 RAA/RDS/CSA，则 ARB 返回全空间，RAA 不收缩，RCM 不增加约束，CAS 为恒等映射。此时 v17 的可行动作集与证书约束逐项等于 v16，故 `Exec_v17=Exec_v16`；一般设置下 v17 只对 `ActionSpace` 取子集并增加合取约束，故 `Exec_v17⊆Exec_v16`。证明：逐项比较定义 657–686 与 v16 定义 627–656；RCM 在 `r≡1` 时 `1−r=0` 不改变路径缺口，CAS 在 `ℓ=L` 时 `A_L=A`。∎ 推论：**v17 的安全性完全继承 v16**，新增风险仅在"错误地认为某单元可靠"，因此稀疏置零与 anytime 有效性是两条不可让步的底线。

**引理 144（可靠性正跃迁的补课下界）** 设维护/换件使已观测单元的可靠性估计上升，但新单元 `c` 无独立样本。在引入 `c` 之前必须满足 `n_c≥n_min`。若借用参考单元 `c_ref` 的先验，且 `TV(P_c,P_{c_ref})≤d`，则仅能声明 `r_c ≥ r_{c_ref} − d`；当 `d≥r_{c_ref}` 时该迁移先验无效，必须实测补课。于是扩张延迟至少为 `n_min/rate(采样)`，且不能通过"整体可靠性上升"绕过。证明：`|p_c−p_ref|≤TV(P_c,P_ref)≤d`，故 `1−p_c ≥ 1−p_ref−d`。∎ 推论：**可靠性正向跃迁只能提高"同一动作单元"的已证下界，不能自动扩大动作空间**；这与 v16 引理 136 的"正向跃迁证书缝隙"同构，但发生在动作维度而非里程碑维度。

## 6. 已知风险与失效模式

1. **选择偏差（自采样本）**：RCM 只看到策略实际执行过的单元，未探索单元永远稀疏并被置零，导致"可靠性"测的是策略惯性。缓解：分层主动采样、心跳单元常驻、离线覆盖集补齐、独立样本审计、对未访问单元显式记录 `UNMEASURED` 而非用先验平滑。

2. **三角界过度保守**：裸并集 + Hoeffding 在高维动作空间与长视界下会把可证体积压到近零，导致系统只能跑 `A_0`。缓解：用 e-process 替代固定样本（log 而非 T 的代价）、按单元分层/聚类复用证据、主动采样、允许"已认证体积"与"探索体积"分离记账。

3. **非平稳与磨损**：单元违例率随关节磨损、电池衰减、温度漂移而上升，历史样本跨分布复用会高估可靠性。缓解：RDS/CUSUM、滑动窗口加 α-spending、失效模式分层、维护后强制补课（引理 144）。

4. **公共模式失效被并集"平均掉"**：并集界虽安全，但若公共模式缺口未显式建模，可能在多个单元同时失效时给出过于粗糙的路径下界。缓解：显式 `ε_common` 项、故障树/共因分析、跨单元相关性监测、独立传感器通道交叉验证。

5. **单元划分的维数灾难**：`Π_ℓ` 在高维动作空间中单元数指数增长，样本被稀释，三角界不可行。缓解：只在任务相关子空间划分、自适应细分（先粗后细）、低维流形嵌入、把连续单元建模为局部 Lipschitz 可靠性场。

6. **可靠性—活性权衡的死锁**：`r_req` 过高或证据饥饿会使 `S*=∅`，只能执行 `A_0`，任务永久停滞。缓解：心跳数据保证 `A_0` 可证、设置"证据饥饿报警"、按里程碑下调 `r_req` 或缩短任务分段、区分"保守"与"卡死"。

7. **正跃迁绕过**：维护/换件/固件升级使已观测单元可靠性上升，若把这一增益直接用于扩张动作空间，会跳过新单元的补课。缓解：引理 144 的强制 `n_min` 独立样本、迁移距离 `TV` 检验、扩张与估计分离记账、扩张前仿真回归。

8. **ARB 贪心在非均匀样本下的次优**：阈值选择在逐单元独立约束下最优，但样本获取成本非均匀、单元价值非均匀时，体积最大不等于任务价值最大。缓解：价值加权体积、采样—授权联合优化、影子价格对偶上升、允许有界次优。

9. **单元与 v16 行为树/里程碑的接口错位**：同一动作在不同 `m*`/`h*` 下可能落入不同单元，导致可靠性证书不可直接复用。缓解：单元定义以 `(action_type, m*, h*)` 为键、跨里程碑证书显式迁移、接口层做键对齐与版本校验。

10. **v17 与 v16–v6 证书栈的累积保守性**：可靠性是又一层合取约束，多层交集后可行域可能收缩到只剩急停。缓解：可靠性作为"贴现价值"而非硬门（除 `r_req` 底线）、选择性放宽需形式化证明、元认证监控保守余量、按任务价值动态分配 `ε_budget`。

## 7. 本轮最大风险

**一句话**：RCM 的证据来自策略自己选择执行过的动作，未探索单元永远稀疏、被置零，于是"可靠性证书"实际认证的是**策略的惯性**而不是**动作空间的可靠性**；当系统用这种自采证据去扩张授权、并借维护/换件带来的可靠性正向跃迁跳过补课时，就会在"证据充分、任意时刻有效、风险严格可加"的表象下执行一个**从未被真正测量过、却因选择偏差而被认证为可靠的动作空间**——即**自我确认的可靠性幻觉**。
