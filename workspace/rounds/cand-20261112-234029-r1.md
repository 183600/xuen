# 第 3 轮迭代（灵感循环 v3：「位姿估计」×「视觉编码器」）—— 把位姿变成整个系统的公共坐标系

> 承接 v2（UIP-01′~15：Gazebo 计分神谕 × 实时性 × 模块化）。本轮不再往上堆一个感知模块，而是先回答 v2 留下的一个更根本的问题：**验证器、技能路由、仿真校准这三件事，说的不是同一种语言**。v2 的 `regressed` 用 2D/几何启发式判断，GSO 用像素/接触谓词打分，技能图用任务名路由；三套表示互不对齐，所以「扰动恢复闭环」始终缺一个**可度量、可迁移、可验证的中间层**。本轮两个灵感词——位姿估计、视觉编码器——恰好提供这个中间层：**SE(3) 位姿是机器人本体感觉、相机标定、桌面物体与仿真之间的公共坐标系**。

**对 v2 的两处硬修正**：

1. **`action_chunk_size` 是握手时定死的全局常数**，不是运行期旋钮。v2 的 ACS「按阶段动态选 k」在接口上不成立；正确做法是**离线选一个全局 `T_a`**，把「反应性」交给块边界重观测 + 块内平滑位姿插值。
2. **不能把「位姿」当作一个黑箱回归头的点估计直接喂给验证器**。公开数据没有物体位姿标签，且 `unseen_object_*` 意味着测试时可能没有 CAD；实例级 6D 位姿对未见物体在定义上就不可得。必须区分 **P1 实例可观测 / P2 类别级可观测 / P3 仅相对/外观可观测**，并对每类给出不同的兜底。

## 1. 先说直觉（不严谨，但先抓住画面）

- 人在桌上做事，不需要「重新识别整张图」。人只需要三件事：**我的手在哪、物体在哪、我要把物体搬到哪**。前两者是位姿，第三者是一个相对位姿目标。视觉的作用不是把整张图压成一个黑箱向量，而是**测量物体相对于我手的位姿**。有了这个量，抓取就是「把手移动到 `T_{o←e}=grasp_offset`」，验证就是「物体是否到达 `T_{o←e}=goal`」，出错恢复就是「目标位姿从满足退回不满足」。
- 上一轮把「撤回」当成一个**视觉事件检测**问题，所以需要「见过撤回」的数据；但公开数据零撤回，检测器无从学。换成位姿语言后，撤回不是一类需要标注的事件，而是**目标谓词从满足变成不满足**：杯子本来在架子上（`m≥0`），现在被拿走了（`m<0`）。**我们不需要「撤回的样本」，只需要「目标的定义」**。这是本轮最关键的直觉转变。
- 视觉编码器的角色也随之改变：它不再是「把图像变成策略特征」的黑箱，而是「**把多视角图像变成一组带协方差的物体位姿 + 语义/可供性**」的测量仪器。黑箱特征可以拟合训练分布，但无法告诉你「杯子离架子还有 3 mm，且这个 3 mm 的置信区间是 ±6 mm」；位姿测量可以。
- 最后一个直觉：**机器人自己的位姿是白送的，物体位姿才是稀缺量**。所以本轮不该去做「从图像估机器人位姿」这种重复劳动，而应把算力全部投到「物体相对末端」这个真正决定成败的量上。

## 2. 再说严谨定义（把直觉钉死）

### 2.1 位姿与相对位姿

记基座系 `b`、左/右末端系 `e_L,e_R`、物体系 `o`、相机系 `c_v`（`v∈{head_L,head_R,wrist_L,wrist_R}`）。位姿 `T_{A←B} ∈ SE(3)` 把 B 系坐标变换到 A 系。

接口已经给了**机器人的精确位姿**，不需要估计：

- `observation.state.*_ee_pose_gripper_base[6]` 直接给出 `T_{e←b}`；
- 关节角 `q` 给出冗余校验（正运动学 `FK(q)` 应与 `T_{e←b}` 一致）；
- 头部相机固定在基座/躯干上，`T_{c_head←b}` 是常数（`camera_params` 给了双目内参与双目外参）；
- 腕部相机与末端刚性连接，`T_{c_wrist←e}` 是常数（**唯一新增的标定量：手眼标定**）。

因此本赛题的「位姿估计」**不是估计机器人位姿，而是估计物体相对机器人/相机的位姿** `T_{o←b}`，并由此得到真正用于决策的量：

`T_{o←e} = T_{o←b} · (T_{e←b})^{-1}`。

**定义 1（相对位姿任务变量）**：对每个操作技能 `k`，其可行域由相对位姿 `T_{o←e}`、夹爪开度 `g` 和可选接触状态 `c` 决定。策略真正需要的不是绝对坐标，而是 `(T_{o←e}, g, c)` 的有序序列。

### 2.2 位姿谓词与进度状态

**定义 2（位姿谓词）**：一个计分步 `s` 的目标集合 `G_s ⊂ SE(3)×R`，以及带符号裕度函数

`m_s(T_{o←e}, g) = dist(T_{o←e}, G_s)`（约定 `G_s` 内 `m≥0`，外 `m<0`）。

进度状态 `state_s(t)` 定义为：

- `done`：`m_s(t) ≥ 0` 且持续 `τ` 帧；
- `ongoing`：`-δ < m_s(t) < 0`；
- `regressed`：曾经 `done`，现在 `m_s(t) < -δ`；
- `fail`：`m_s(t) ≤ -Δ` 或超时。

**这就是对 v2 `regressed` 的严格化**：撤回 = 目标集合的成员关系翻转，而不是「看起来像撤回」的视觉模式。它天然不需要撤回样本，只需要目标的几何定义。

### 2.3 位姿感知编码器

**定义 3（位姿感知编码器）**：

`f_θ(I_{1:V}, l, {T_{c_v←b}}) = (z_sem, { (o_j, mask_j, T̂_{o_j←b}, Σ_j, vis_j) }_{j=1..J}, {κ_j})`

其中 `I_v` 是第 v 路图像，`l` 是语言，`T_{c_v←b}` 是已知相机位姿，`z_sem` 是语言对齐的语义 token，`T̂` 是物体位姿估计，`Σ` 是 6×6 协方差（在 SE(3) 切空间），`vis` 是可观测性掩码，`κ_j` 是关键点/可供性。三条硬要求：

- **背景/相机不变性**：位姿输出只依赖物体几何与相机外参，不依赖背景纹理；`f(I ∘ bg)=f(I)`。
- **场景整体位移等变性**：若物体与相机一起做 `g∈SE(3)`，则 `T̂ → g·T̂`，而相对位姿 `T_{o←e}` 与 `z_sem` 不变。
- **不确定性显式**：`Σ_j` 必须可信；没有 `Σ` 的位姿只能叫点估计，不能进验证器。

### 2.4 泛化五轴在位姿语言下的含义

| 泛化轴 | 位姿语言下的含义 | 位姿能否解决 |
|---|---|---|
| 未见物品 | 无 CAD/实例模型 ⇒ 实例 6D 位姿无定义 | **部分**：类别级/关键点/相对位姿 |
| 位置 | 物体 `T_{o←b}` 改变 | **是**：相对位姿等变 |
| 干扰物 | 额外物体进入视野 | **是**：掩码/槽位分离 |
| 背景 | 纹理/光照改变 | **是**：位姿不变性 |
| 人为干扰 | 目标位姿被反向改变 | **是**：谓词翻转，不需要撤回样本 |

## 3. 位姿能覆盖什么、不能覆盖什么（本轮最重要的诚实边界）

把 32 任务按「目标是否可由位姿谓词表达」分三类：

- **P1 刚体可观测**：插网线、叠碗、放相框、装手机、开锁、排列餐盘……目标主要是刚体相对位姿。
- **P2 形变/接触状态**：叠毛巾、拉拉链、收拾书包、整理文具……位姿只能给出「大致到位」，闭合/褶皱/拉链齿合需要外观或接触代理。
- **P3 流体/内部状态**：倒药、针管转移……位姿只能判断容器姿态，液量/是否倒出不可直接观测。

这解释了为什么不能把 v2 的单一 `regressed` 检测器换成「位姿万能论」：**位姿是强项，但不是全部**。对 P2/P3，位姿谓词只负责「容器/工具到位」，最后的状态仍要外观或夹爪/接触信号兜底。

## 4. 瓶颈假设（v3 更新）

- **H1′（最高杠杆）**：在零撤回数据下，**解析位姿谓词**比学习式 2D 撤回检测器更可靠：前者只需要目标定义，后者需要事件样本；且前者对位置/背景/干扰物天然不变。
- **H2′**：位姿误差的**方向**比大小更关键。插入/堆叠/放置的误差主要沿任务轴；沿轴精度可由腕部近距相机与多视几何显著改善，横向误差可由头部双目改善。
- **H3′**：接口给的是**开环动作块 + 全局固定 `T_a`**，所以实时性不是「运行期变块长」，而是「块边界重观测 + 块内平滑位姿插值 + 选择性发送相机」。
- **H4′**：位姿是 sim 与 real 的**共同可测量**。把 GSO 的评分从像素/接触谓词改成位姿谓词，sim-to-real 的差距就变成可测的位姿分布差距，而不是不可解释的像素差距。
- **H5′**：位姿估计的**自信错误**会同时污染验证、重定向和仿真校准（相关失效），比 2D 启发式的「各自犯错」更危险；因此必须把位姿当测量量（带 `Σ` 与 `vis`），而不是真值。

## 5. 候选、合并与修剪 → v3 清单

- **升级**：UIP-01′ → **UIP-01″**（位姿谓词滚动验证）；UIP-09′ → **UIP-09″**（位姿撤回检测）；UIP-11 → **UIP-11′**（位姿空间计分神谕）；UIP-12 → **UIP-12′**（位姿随机化扰动工厂）；UIP-14 → **UIP-14′**（位姿目标技能图）；UIP-15 → **UIP-15′**（协方差感知安全阀）。
- **新增（命中两词）**：**UIP-16 PAE**（位姿感知多视编码器）、**UIP-17 PPV**（位姿谓词验证器）、**UIP-18 DRP**（双率位姿伺服）、**UIP-19 CRT**（规范相对位姿重定向）、**UIP-20 PSC**（位姿空间 sim-real 校准）。
- **修剪/改写**：UIP-13 ACS → **UIP-13′ GCS**（全局块长离线选择，不再假设运行期变长）；UIP-05 LCAG 保留但并入 PAE 的语义槽位；UIP-02′、UIP-08′ 保留。
- **封存**：不新增独立世界模型；不引入外部 VLM/6D 基础模型作为推理期模块（合规风险）。

## 6. 本轮最大风险

**一句话**：位姿的自信错误会同时污染验证、重定向和仿真校准——它看起来像精度而不是不确定性；若没有协方差门控与位姿无关的兜底通道，v3 会比 v2 错得更一致、更难被重试纠正。

**→ 本轮最值得押注：UIP-01″（位姿谓词滚动验证）× UIP-16（位姿感知编码器）× UIP-17（谓词库）组成的「几何验证闭环」**——它把 v2 依赖撤回样本的视觉检测，改成只依赖目标几何定义的解析判定；再用 UIP-20 把仿真与真机对齐到同一坐标系，使「扰动恢复」第一次成为可度量、可迁移、可复现的工程问题。

## 2. 旗舰深潜：UIP-01″ · RHPV-P（Rolling-Horizon Progress-Verified, Pose-grounded）

### 2.1 机制

动作块仍然开环执行，但每个块边界用**位姿谓词**核验当前计分步 `s`：

```text
m_s(t) = dist(T_{o←e}(t), G_s)        # G_s 内 m≥0
state_s(t) = done       if m_s ≥ 0 for τ frames
             regressed  if was done and m_s < -δ
             ongoing    if -δ ≤ m_s < 0
             fail       if m_s ≤ -Δ or timeout
```

与 v2 的差别：

- v2 用 2D/图像启发式判 `regressed`，需要「撤回正样本」；公开数据零撤回 ⇒ 学不到。
- v3 用**目标集合 `G_s` 的成员关系**判 `regressed`；`G_s` 由任务几何解析给出 ⇒ **零撤回样本也能判**。
- v3 的判定带**协方差**：只有在 `Σ` 沿任务轴足够小、且 `vis` 认为物体可观测时才下结论；否则保持 `ongoing` 并触发主动感知（UIP-16/18）。

### 2.2 为什么这是「零样本撤回检测」

设真实状态 `T_t`，估计 `T̂_t = T_t + e_t`。若 `e_t` 小且 `m_s` 对 `T` 连续，则 `m_s(T̂)` 与 `m_s(T)` 同号（除边界带）。撤回事件定义在 `m_s(T)` 上，不涉及「撤回长什么样」。因此：

> **检测撤回所需的知识 = 目标集合 `G_s` 的定义；不需要任何撤回演示。**

这正是 v2 最大数据空白（人为撤回零覆盖）的正解，也是本轮相对 v2 最实质的推进。

### 2.3 状态机与兜底

```text
if state == done:        g += 1; redo = 0; plan next goal
elif state == regressed: redo += 1; replan same goal (pose-relative)
elif state == fail:      redo += 1; fallback to pose-free visual servo
else:                    continue current chunk
```

- `regressed` 触发后，用 UIP-19 直接把目标位姿重新发给末端，而不是重放旧轨迹。
- 若 `Σ` 过大或 `vis=0`，**不判 `regressed`**，转 UIP-18 的主动感知/视觉伺服，避免「自信错误 + 反复重做」。

## 3. UIP-16 · PAE（Pose-Aware multi-view Encoder）

### 3.1 输入与输出

**输入**：4 路 RGB（`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`）、语言 `l`、已知相机位姿 `T_{c_v←b}`、机器人状态 `(q, T_{e←b}, g)`。

**输出**：

```text
z_sem                         # 语言对齐的稠密语义 token（给策略/可供性）
{ (o_j, mask_j, T̂_{o_j←b}, Σ_j, vis_j, κ_j) }   # 物体槽位
```

- `T̂`：物体在基座系的 6D 位姿（旋转用 6D 表示，平移用米）。
- `Σ`：6×6 协方差（SE(3) 切空间），由异方差损失训练。
- `vis`：沿 6 个自由度/任务轴的可观测性掩码；遮挡或超出视锥时为 0。
- `κ_j`：关键点/可供性（抓取点、插入轴、容器口、铰链轴）。

### 3.2 结构

```text
每路图像 → patch tokens
          + 相机 token（Plücker ray / 外参 embedding）
          + 时间 token
                ↓
        共享 ViT 骨干（跨视角 attention）
                ↓
     ┌──────────┴──────────┐
  稠密语义头 z_sem      物体槽位解码器（J 个 query）
                            ↓
              class / mask / keypoints / pose / covariance
                            ↓
              几何精化：PnP / ICP / 类别规范空间
                            ↓
              多视融合 + SE(3) 时序滤波
```

**关键设计：双路输出，不是硬瓶颈。** 策略同时看到 `z_sem`（稠密、抗位姿失败）和位姿槽位（结构化、可验证）。这样即使位姿头出错，策略仍有一条视觉特征退路；但验证器只在高置信时使用位姿。

### 3.3 三档可观测性（不夸大）

| 档 | 条件 | 位姿表示 | 训练/推理 |
|---|---|---|---|
| **P1 实例级** | 有 CAD 或训练集中出现过 | `T_{o←b} ∈ SE(3)` + 网格 | PnP/ICP 精化；标签来自 Gazebo |
| **P2 类别级** | 同类未见实例 | 类别规范空间 + NOCS/关键点 + 尺度 | 类别级规范位姿；关键点三角化 |
| **P3 相对级** | 无类别/无形变先验 | 抓取可供性 + 相对关键点 + 视觉伺服 | 不输出绝对 6D；用相对位姿/外观 |

对 `unseen_object_*`，**P1 在定义上不可得**；必须自动落到 P2/P3，并用 `vis` 显式标注。这是本方案与「所有物体都估 6D」的夸大方案的分界线。

### 3.4 多视几何与传感器路由

- 头部双目已标定（`b≈58.25 mm`，`f≈282.4 px`，`rectified=true`）：可用关键点视差直接三角化，给出**米制尺度**。
- 腕部相机与末端刚性连接：`T_{c_wrist←e}` 一次手眼标定；腕部 RGB 在运动中获得视差，或由头部双目提供尺度锚。
- **深度误差随距离平方增长**（推导见 §8.1）：头部双目在 0.5 m 处、0.5 px 视差误差 → 约 **7.6 mm** 深度误差；腕部近距（0.15 m）→ 约 **1.6 mm**。因此**接触密集步必须路由到腕部近距视角**，远距搬运才用头部双目。
- 多视融合：按 `Σ^{-1}` 加权；遮挡时降权，`vis` 置 0。

### 3.5 训练与标签（公开数据无物体位姿）

```text
L = L_pose(ADD/ADD-S + geodesic) + L_mask + L_sem(语言对比)
  + L_geo(多视重投影/光度一致性) + L_time(位姿平滑/速度一致)
  + L_uncertainty(异方差 NLL)
```

标签来源（按成本排序）：

1. **Gazebo 位姿标签**（UIP-11′/12′）：已知物体位姿，直接监督。
2. **回放式自动标注**：用数据集中记录的机器人 `state/action` 驱动 Gazebo 中的 G1，优化物体初始位姿使渲染与真实视频对齐（analysis-by-synthesis）→ 得到物体位姿序列。公开数据只有机器人轨迹，没有物体标签，这条管线把「有轨迹」变成「有位姿」。
3. **真实数据自监督**：头部双目 + 腕部运动的多视重投影/光度一致性；无需标签。
4. **少量人工关键点**：只标 2D 关键点用于校准，不标 6D。

**合规**：以上教师/基础模型只在**离线**使用；推理期只有共享骨干 + 位姿头，满足「单模型」。不把外部 6D 基础模型作为在线模块。

## 4. UIP-17 · PPV（Pose-Predicate Verifier）

### 4.1 谓词库

| 谓词 | 裕度 `m_s`（示例） | 主要自由度 | 典型任务 |
|---|---|---|---|
| `Align(axis_o, axis_e, θ_max)` | `m = cos θ_max − cos θ(axis_o, axis_e)` | 旋转 2 DoF | 插插头、插网线、开锁 |
| `Insert(depth)` | `m = (p_tip − p_port)·n − d_goal` | 平移 1 DoF（沿轴） | T26 网线、T10 插头、T12 钥匙 |
| `Stack(order, h)` | `m = min(m_vert, m_horiz)`；`m_vert = z_obj − z_support − h` | 平移 3 DoF + 偏航 | T27 叠碗、T20 纸杯 |
| `Place(pos_tol, yaw_tol)` | `m = min(r_tol − ‖p−p_goal‖, yaw_tol − |Δψ|)` | 平移 3 + 偏航 | T07 相框、T13 试管 |
| `Rotate(θ_goal)` | `m = θ_max − |θ − θ_goal|` | 旋转 1 DoF | T14 拧盖、T12 开锁 |
| `Close(gap_max)` | `m = gap_max − gap` | 平移/铰链 | T17 笔盒、T29 手机壳 |
| `Pour(tilt_min)` | `m = min(tilt − tilt_min, mouth_above_target)` | 旋转 + 位置 | T14 倒药、T32 针管 |
| `Hold(g_min, contact)` | `m = min(g − g_min, contact)` | 夹爪 + 接触 | 所有抓取步 |
| `Deform(keypoints)` | `m = mean_i(d_i − d_i^goal)` | 关键点/轮廓 | T16 毛巾、T19 拉链 |

### 4.2 32 任务的谓词可观测性（节选）

| 任务 | 关键计分谓词 | 档 | 备注 |
|---|---|---|---|

### 4.3 与 UIP-09″ 的关系

UIP-09″ = UIP-01″ 的 `regressed` 分支 + 重做策略。区别只在「检测到撤回之后做什么」：

- 优先用 UIP-19 重新生成目标位姿（几何重定向）；
- 若目标物体已不可见/被拿走，重新定位物体（PAE 全图搜索）；
- 若连续重做超预算，UIP-15′ 熔断，转保守的「保前置步骤分」策略。

## 5. UIP-18 · DRP（Dual-Rate Pose servoing）

### 5.1 接口现实

`action_chunk_size=T_a` 是**握手时定死的全局常数**，不能按阶段变长。因此「反应性」只能来自：

1. **块边界重观测**：每个 `get_action` 都重新估计位姿，必要时重规划；
2. **块内平滑位姿轨迹**：把「当前 `T_{e←b}` → 目标 `T_{e←b}`」在 SE(3) 上插值成 `T_a` 个目标位姿；
3. **选择性发送相机**：`obs_delta_indices` 只声明必要键，减少 JPEG 与延迟。

### 5.2 轨迹生成

```text
T_target = ΔT_skill^{-1} · T̂_{o←b}
T(s) = T_current · exp(s · log(T_current^{-1} T_target)),  s = 1/T_a … 1
```

用最小 jerk 时间重参数化压平滑；接触步降低速度、提高刚度；搬运步提高速度。输出 `ee` 模式时直接是目标位姿；`joint` 模式时用 IK 转关节目标（需检查奇异/关节限位）。

### 5.3 为什么不是「双率反馈」

必须诚实：块内评测端不回调策略，所以块内没有真正的视觉反馈；DRP 的「双率」是**块边界慢率视觉 + 块内快率位姿插值**，不是快率闭环。真正的快率闭环只能靠 `T_a` 取小（全局固定）。这一点修正了 v2 ACS 的过度承诺。

### 5.4 全局 `T_a` 的离线选择

用一个标定集扫 `T_a ∈ {1,2,4,8,16}`，指标：

`J(T_a) = 成功率 + λ·步骤分 − μ·延迟方差 − ν·动作抖动`

在 32 任务上取一个折中；若允许按任务提交不同 metadata，则按任务选。默认假设**单次提交全局 `T_a`**。

## 6. UIP-19 · CRT（Canonical Relative-pose ReTargeting）

### 6.1 技能 = 相对位姿目标

每个技能 `k` 定义一个规范目标

`T_{o←e} = ΔT_k`（例如抓取偏移、插入前对齐、堆叠上方 5 cm）。

给定当前物体位姿 `T̂_{o←b}`，末端目标为

`T_{e←b}^{target} = (ΔT_k)^{-1} · T̂_{o←b}`。

**等变性**：若物体整体做 `g∈SE(3)`，则 `T̂_{o←b} → g T̂_{o←b}`，目标同步变为 `(ΔT_k)^{-1} g T̂_{o←b}`。只要策略/技能以 `T_{o←e}` 为输入，其对场景整体位移**等变**、对背景**不变**。

### 6.2 与 UIP-14′ 的结合

技能图节点 = 技能模块（抓/放/插/倒/拉链/折叠/堆叠/分拣/开合/挑取），边 = 计分步顺序。每个节点只需要：

- 一个规范相对位姿目标 `ΔT_k`；
- 一个可选的外观/接触谓词（形变/流体）；
- 一个完成后要满足的 `G_k`。

这样 UIP-14′ 的「模块化」不再是「多个头」的软路由，而是**共享骨干 + 位姿目标接口**的硬组合；换任务只是换图，不需要换模型。

### 6.3 控制空间选择

- `ee` 模式：直接输出 `T_{e←b}^{target}`，与 CRT 天然对齐；适合位姿技能。
- `joint` 模式：需要 IK；更接近数据集的关节动作分布，可能更平滑。
- **建议**：先做 `ee` 模式的离线回放验证；若评测端 IK 行为未知或奇异频发，回退 `joint` + IK 兜底。握手只能选一次，需用公开回放/本地 stub 验证后再定。

## 7. UIP-20 · PSC（Pose-Space Calibration）—— GSO/DRF 的升级

### 7.1 用位姿定义 sim-real 差距

不再用像素差或接触谓词差，而用**位姿分布差**：

`d_P(P_sim, P_real) = W_2({T_{o←e}^{sim}}, {T_{o←e}^{real}})`，

或逐任务的平均测地误差 `E‖log(T_sim^{-1} T_real)‖`。GSO-P（UIP-11′）直接在仿真里算 `m_s(T_{o←e})`，得到**与真机同口径**的步骤分代理。

### 7.2 校准锚点

在少量真机 episode 上拟合每个任务的仿射校准：

`m_real ≈ α_s · m_sim + β_s`

用 `α_s, β_s` 修正 GSO 分数；若 `α_s` 远离 1，说明该任务的仿真位姿/接触不可信，降权或仅作结构代理。

### 7.3 位姿空间域随机化

UIP-12′ 的随机化不再只随机纹理/光照，而是随机：

- 物体初始位姿、抓取偏移、堆叠高度；
- 相机外参微扰（模拟标定误差）；
- 扰动时机、速度、方向（对应 `human_*` 的「反向撤回」）；
- 延时/丢帧（模拟网络）。

这样 DRF-P 生成的是 **(扰动前位姿 → 撤回位姿 → 恢复位姿)** 三元组，直接训练 UIP-09″ 的恢复策略。

## 8. 关键推导

### 8.1 双目深度误差与传感器路由

针孔双目：`Z = f b / d`，视差误差 `σ_d` 传播为

`σ_Z = (Z² / (f b)) · σ_d`。

代入头部双目 `f≈282.37 px, b≈58.25 mm`：

| 距离 `Z` | `σ_d=0.5 px` | `σ_d=1.0 px` |
|---|---|---|
| 0.2 m | 1.22 mm | 2.43 mm |
| 0.3 m | 2.74 mm | 5.47 mm |
| 0.4 m | 4.86 mm | 9.73 mm |
| 0.5 m | 7.60 mm | 15.20 mm |
| 0.7 m | 14.89 mm | 29.79 mm |

腕部 IR 双目（`f≈388.65, b≈18.05 mm`，注意接口只发 RGB，深度需由 RGB/运动估计）：

| 距离 `Z` | `σ_d=0.5 px` | `σ_d=1.0 px` |
|---|---|---|
| 0.10 m | 0.71 mm | 1.43 mm |
| 0.15 m | 1.60 mm | 3.21 mm |
| 0.20 m | 2.85 mm | 5.70 mm |
| 0.30 m | 6.41 mm | 12.83 mm |

**设计含义**：0.5 m 处头部双目在 0.5 px 噪声下只有 ~7.6 mm 深度精度，不足以判定 5 mm 级插入；接触步必须切到腕部近距（~1–2 mm）。这就是「传感器路由」的硬依据，而不是拍脑袋。

### 8.2 验证门限 vs 位姿误差

设裕度 `m_s` 对位姿误差 `L`-Lipschitz：`|m_s(T̂)−m_s(T)| ≤ L‖e‖`。要在容差 `δ`、误判率 `α` 下可靠判定，需

`σ_e ≤ δ / (L · z_{1−α/2})`。

取 `L=1, α=0.01, z=2.576`：

| 任务容差 `δ` | 允许位姿误差 `σ_e` |
|---|---|
| 3 mm | 1.16 mm |
| 5 mm | 1.94 mm |
| 10 mm | 3.88 mm |
| 20 mm | 7.76 mm |

**设计含义**：5 mm 插入需要 ~2 mm 级位姿精度；这正是腕部近距 + 多视融合的目标；达不到时不要假装能判，应降级为视觉伺服/接触探索。

### 8.3 不变性/等变性命题

**命题**：相对位姿 `T_{o←e}` 对背景变换不变，对物体整体刚体变换等变。

*证明*：背景变换不改变 `T_{o←b}` 与 `T_{e←b}`，故 `T_{o←e}=T_{o←b}(T_{e←b})^{-1}` 不变。物体做 `g`：`T_{o←b}→gT_{o←b}`，故 `T_{o←e}→gT_{o←e}`。若目标集合 `G_s` 同步变换，则 `m_s` 不变；若策略以 `T_{o←e}` 为输入，则输出动作同步等变。∎

**推论**：任何直接定义在像素坐标上的谓词 `p(u,v)` 都不具备该不变性，除非显式反投影到 3D 并补偿相机位姿。这是「把谓词抬到位姿空间」的核心理由。

### 8.4 相关失效（correlated failure）

设验证器与重定向器共享同一个位姿估计 `T̂=T+e`。若 `e` 大但 `Σ` 低估（自信错误），则：

1. 验证器可能把未完成判成 `done`（漏检撤回）；
2. 重定向器把末端送到错误目标；
3. 重试仍用同一错误 `T̂`，形成稳定错误吸引子。

因此 v3 必须满足两条**独立性约束**：

- **测量独立性**：至少两路几何/外观证据（头部双目 vs 腕部近距）不一致时，降低置信度，不判 `done`/`regressed`。
- **兜底独立性**：保留一条**不依赖物体位姿**的通道（图像空间视觉伺服、夹爪开合/接触、末端跟踪误差），在 `Σ` 过大时接管最后几毫米。

### 8.5 sim-real 的位姿空间界

若仿真与真机的相对位姿分布满足 `W_2(P_sim,P_real) ≤ ε`，且成功谓词 `m` 为 `L`-Lipschitz、裕度 `δ`，则在 Lipschitz 传输/线性化假设下，

`|P_success^sim − P_success^real| ≤ L ε / δ`。

因此**要缩小 sim-real 成功率差，应缩小位姿分布差**，而不是缩小像素差。这为 UIP-20 提供了可操作的校准目标：先测 `ε`，再决定是否相信 GSO 分数。

### 9.1 位姿感知编码器

```python
class PoseAwareEncoder(nn.Module):
    def forward(self, obs):
        # obs: 4 RGB + language + robot state + known extrinsics
        toks = []
        for v, img in obs.images.items():
            t = self.patch_embed(img)
            t = t + self.cam_embed(v, obs.T_cam_base[v])   # Plücker ray
            t = t + self.time_embed(v)
            toks.append(t)
        z = self.backbone(torch.cat(toks, dim=1))          # cross-view attention
        z_sem = self.sem_head(z)
        slots = self.slot_decoder(z, self.queries)         # J object queries
        for s in slots:
            s.mask = self.mask_head(s)
            s.kp   = self.kp_head(s)
            s.pose = self.pose_head(s)                     # 6D rot + t
            s.cov  = self.cov_head(s)                      # Cholesky 6x6
            s.vis  = self.vis_head(s)                      # observability mask
        slots = self.geometric_refine(slots, obs)          # PnP/ICP/category
        slots = self.multi_view_fuse(slots, obs)           # covariance-weighted
        slots = self.temporal_filter(slots, obs)           # SE(3) filter
        return z_sem, slots
```

### 9.2 位姿谓词验证器

```python
def verify(task, s, slots, gripper, robot):
    o = match_object(task, s, slots)          # 目标物体
    if o is None or o.vis[task.axis] == 0:
        return "unobservable", 0.0, None
    T_oe = o.T_base @ inv(robot.T_ee_base)    # 相对位姿
    m, axis = task.predicate(s).margin(T_oe, gripper)   # 带符号裕度
    sigma = project_cov(o.cov, axis)          # 沿任务轴的 1D 标准差
    conf = margin_confidence(m, sigma)        # e.g. sigmoid(m / sigma)
    if conf < task.conf_thr:
        return "ongoing", conf, T_oe          # 不下结论
    if m >= 0 and task.was_done(s):
        return "done", conf, T_oe
    if task.was_done(s) and m < -task.delta:
        return "regressed", conf, T_oe
    if m <= -task.Delta:
        return "fail", conf, T_oe
    return "ongoing", conf, T_oe
```

### 9.3 旗舰策略（固定 `T_a` + 位姿重定向）

```python
class RHPVP_Policy:
    def __init__(self, encoder, skill_graph, task_lib, T_a, conf_thr=0.6,
                 max_redo=2, sigma_gate=None):
        self.T_a = T_a
        self.g = 0
        self.redo = 0

    def reset(self):
        self.g = 0; self.redo = 0; self.buf = []

    def get_action(self, obs):
        z_sem, slots = self.encoder(obs)
        state, conf, T_oe = verify(self.task, self.g, slots,
                                   obs.gripper, obs.robot)
        if state == "done":
            self.g += 1; self.redo = 0
        elif state == "regressed" and self.redo < self.max_redo:
            self.redo += 1                       # replan same goal
        elif state == "fail" and self.redo < self.max_redo:
            self.redo += 1                       # fallback to servo

        # 选择技能节点与规范相对位姿目标
        skill = self.skill_graph.node(self.task, self.g)
        T_e_target = retarget(skill, slots, obs)  # UIP-19
        # 块内平滑插值；输出固定 T_a 个位姿或关节目标
        chunk = smooth_se3_traj(obs.T_ee_base, T_e_target, self.T_a)
        return self.pack(chunk, obs, z_sem, slots)
```

## 11. 合规与风险（v3 重点）

- **单模型合规**：PAE 与策略共享骨干；位姿头是同一模型的辅助头；外部 6D/VLM 只在离线当教师，推理期不加载。若评测方对「辅助头」有异议，退化方案是**纯几何前端**（双目三角化 + PnP），不引入任何额外学习模型。
- **位姿不可观测**：P2/P3 不输出实例 6D；`vis` 显式置 0；验证器不硬判。不能把「类别级位姿」伪装成「实例级位姿」。
- **相关失效**：必须保留位姿无关的兜底通道；Σ 门控 + 多视一致性 + 夹爪/接触信号三重校验。
- **接口红线**：`T_a` 全局固定；`ee`/`joint` 互斥；形状、dtype、token、时间轴严格按 README；返回块内动作要平滑，避免可信度异常。
- **仿真过拟合**：GSO-P 只在位姿空间可信；像素/接触仍以真机锚点为准；`α_s` 偏离 1 的任务降权。
- **计算/延迟**：位姿头与多视融合会增加延迟；用 `obs_delta_indices` 削减相机与堆叠帧，必要时降分辨率；p99 延迟必须可解释。

## 13. 本轮最大风险 & 押注

**一句话**：位姿的自信错误会同时污染验证、重定向和仿真校准——它看起来像精度而不是不确定性；若没有协方差门控与位姿无关的兜底通道，v3 会比 v2 错得更一致、更难被重试纠正。

**→ 押注：UIP-01″（位姿谓词滚动验证）× UIP-16（位姿感知编码器）× UIP-17（谓词库）组成的「几何验证闭环」**，用 UIP-20 把仿真与真机对齐到同一 SE(3) 坐标系。它把 v2 依赖撤回样本的视觉检测，改成只依赖目标几何定义的解析判定；一旦位姿精度达标，就能以零撤回数据直接吃到规则里白纸黑字的「反向撤回」步骤分。
