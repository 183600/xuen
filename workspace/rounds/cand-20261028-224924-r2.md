# 第 2 轮（新循环）· DQ-MEM：数据质量门控的记忆检索，把 33k 演示变成可查的赛场先验；用轮足式双频执行承接 CHUNK-SERVO

> 检索/复核日期：**2026-10-28（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。
>
> 说明：`research.md` 上一版是第 12 轮 CHUNK-SERVO；本轮是灵感循环重置后的**第 2 轮**，三个词是「**数据质量**」「**记忆检索**」「**轮足机器人**」。不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是把它们的“观测/控制”层继续往下压到“**数据可用性 + 测试时记忆 + 任务特定 stance**”。

## 0. 先给结论：榜首不到 30%，但 29.7% 不是 SOTA，是预览；真正的共享瓶颈不是模型大小，而是“数据可用性 + 测试时记忆 + 接触段执行”

截至 2026-10-28，官网首页/榜单显示 8 个条目：MolmoAct 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。头尾只差 **9.2pp**，看起来像“架构差距不大”；但这份榜单是 `gen_leaderboard.py` 生成的**预览数据**，不是可复现真机结果（证据见 §1.1）。所以不能把 29.7% 当 SOTA，也不能从榜单任务排名反推难度。

即便只看公开技术路线，头部方案也呈现同一个偏向：

1. **它们主要在解“语义/场景泛化”**：MolmoAct2 的 3D 动作推理、WALL-OSS 的多 embodiment 预训练、DreamZero 的视频世界模型、π0.5 的开放世界 co-training、GigaBrain-0 的世界模型生成数据，都是“看得懂、去得对”。
2. **它们没有解“最后 3 厘米”**：多数头部方案最终以 action chunk 执行，chunk 内不看新图（DreamZero 虽 7Hz 闭环，但接入挑战赛固定 chunk/RTT 后仍会出现开环段）；接触、插入、挂杯、拉拉链、拧瓶盖发生在最后几毫米/几百毫秒，语义先验帮不上。
3. **它们没有解“测试时记忆”**：33k 条演示只在训练时用一次；推理时模型看不到“这个任务上次成功时夹爪相对杯架是什么位姿、下身体高度是多少、失败后怎么恢复”。
4. **它们没有解“任务特定 stance”**：挑战赛是站立 G1，但数据里的 `pivot/height/lower_body` 不是常量；不同任务的下身体高度、腰部姿态、`pivot_4` 明显不同。把所有 `pivot` 置零会丢掉一个便宜的先验。
5. **它们没有把本赛事特有的数据错位当成一等公民**：33k 条不是 33k 条同样可用的数据；动作标签普遍领先状态约 3 帧（100ms），头部相机 fx 跨任务从 186 到 296，夹爪动作范围 0–4.5 而 README 写 5.5→0，训练视频是 AV1 而线上是 JPEG q95。MolmoAct2 过滤 DROID/SO-100、Spirit 强调“多样而非干净”，都是数据策略，但没有修这些监督对齐问题；直接混训会把噪声学进去。

所以本轮的押注是 **DQ-MEM**：

> **先用 DQ-SCORE 给 33k 条演示做“可用性”而不是“干净度”打分；再把真正可用的关键帧/片段做成只读的三层记忆（TASK-MEM / CONTACT-MEM / RECOVERY-MEM）；推理时只把记忆当作目标位姿、相位、stance 和恢复先验，喂给同一个官方 WLA + 确定性伺服；用 WHEEL-LEG ROUTER 在“轮式快速全局”和“足式慢速局部”之间切换执行频率。**

一句话：**不是再训一个更大的 VLA，而是把 169 小时演示变成测试时可查的“赛场笔记”，并让同一个模型在自由空间跑快、在接触段跑慢。**

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 明确不做什么 |
|---|---|---|
| **数据质量** | **DQ-SCORE**：动作-状态对齐、相机标定一致性、目标后果加权、覆盖度、恢复段保留；用于 WLA action-head 微调采样权重和记忆入库优先级 | 不把“平滑/成功/干净”当质量；不把失败/犹豫/重试段全删掉；不把 33k 条等权混训 |
| **记忆检索** | **TASK-MEM**（任务级：目标锚点、相位图、pivot/height/stance、步数预算）+ **CONTACT-MEM**（接触级：接触前相对位姿、腕部目标图、插入轴、夹爪开度）+ **RECOVERY-MEM**（恢复级：犹豫/重抓/失败后恢复片段）；只读、非参数、控制器外挂 | 不做第二个学习策略；不做在线权重更新；不把检索结果直接当动作输出；不用未批准的第二个视觉大模型 |
| **轮足机器人** | **WHEEL-LEG ROUTER**：wheel=自由空间长 chunk + 全局记忆；leg=接触段短 chunk + 局部伺服 + 局部记忆；按相位/接触距离/检索 margin/扰动切换频率与增益 | 不做轮式底盘；不把 G1-D 当挑战赛硬件；不在 `control_space` 之间动态切换（接口是固定 `joint` 或 `ee`） |

本轮一句话押注（详见 §8）：**最值得押注的是 DQ-MEM 的“质量门控的任务级 stance + 接触级目标”记忆，而不是再堆一个更大的 VLA。**

## 1. 本轮新核实的事实（只列会改变方案的）

### 1.1 榜单：8 个条目、256 条 run，但它是脚本生成的预览，不是真机 SOTA

官方 `leaderboard_data.json`（2026-10-28 通过 `r.jina.ai` 抓取）和 `runs.html` 显示：

- 8 个模型 × 32 任务 = **256 条 run**；
- JSON 的 `generated_from` 是 **`gen_leaderboard.py`**；
- 对每个模型做 `step_score ~ success_rate` 回归，**R² > 0.999999，最大残差 < 0.006**；斜率在 **1.305–1.371** 之间；
- 每任务名义上 10 次 trial，但 256 个成功率里有 **232 个不是 10% 的整数倍**（例如 27.29%、27.85%、38.43%）；
- 详情页 32 个任务的“评测视频”全部是“测试视频占位，后续可替换为真实视频文件”；
- 8 个模型的 32 维任务成功率两两相关，平均 off-diagonal 相关系数只有 **约 0.098**（平均绝对相关约 0.14）；如果任务难度是真实的，不同模型在同一任务上应该正相关。

**结论**：29.7% 只能当“赛事方预览上限/难度信号”，不能当 SOTA、不能当任务难度表、不能反推失败分布。头部方案的“做法与瓶颈”要看公开论文/模型卡，而不是看这份 JSON 的名次。

MolmoAct2 的官方博客自己把两条弱点写得很清楚：**（1）一次规划 10–30 步、整批开环执行，batch 之间没有平滑；（2）只对 SO-100、双臂 YAM、Franka 开箱即用，人形/带手平台要额外训练。** 这两条正好对应本赛事的 chunk/接触瓶颈和 G1+Dex1 适配问题；它在 Franka 上的 87.1% 不能直接外推到 UniBot。

**共同瓶颈（比名次更重要）**：

1. **都是“语义/场景泛化”模型，不是“接触控制器”**。它们能把“杯子→杯架”对齐到厘米级，但挂杯、插网线、拉拉链要求毫米级和力/滑移感知；API 没有力/触觉，只能靠视觉 + 任务先验。
2. **chunk 内不看新图**。官方 WLA 默认 30 步 @30Hz = 1s；远程 RTT 再叠加。接触段 1s 开环，足够把“差 2mm”变成“撞歪/掉杯”。
3. **没有测试时记忆**。33k 演示只在训练时出现；推理时模型不知道“这类任务上次成功时夹爪相对目标是什么位姿、下身体多高、失败后怎么退”。
4. **没有任务特定 stance**。数据里 `pivot_4` 0.11–0.21、height 最低 0.608、`angle_z` 可到 ±0.8；把所有 `pivot` 置零不是“安全”，是丢先验。
5. **本赛事特有的数据错位没有被当成一等公民**。动作-状态错位 100ms、头部 fx 跨任务差 1.6 倍、夹爪尺度不一致、AV1/JPEG 域差；这些不是“多训一会”能自动消失的。MolmoAct2 过滤 DROID/SO-100、Spirit 强调多样而非干净，都是数据策略，但没有修这些监督对齐问题。

### 1.3 数据审计：33k 条不是 33k 条同样可用的数据

32 个 HF 数据集 `meta/info.json` + `meta/stats.json`（2026-10-28 逐个读取）合计：

| 项 | 数值 |
|---|---:|
| episodes | **33,276** |
| frames | **18,282,246** |
| 时长 | **169.28 h**（30 fps） |
| 任务数 | 32 |
| 单任务 episodes | 969–1,533 |
| 单任务平均时长 | 6.2 s（HangCup）–37.6 s（ToolboxStorage） |
| 视频 | AV1，yuv420p，480×640，30fps |

本轮把 32 个任务的相机/动作统计重新拉了一遍，得到四个会改变方案的结论：

1. **腕部相机有内参，而且很稳定**：`wrist_left/right.color.camera_matrix` 存在，`fx ≈ 432.9–437.5`。第 12 轮“腕部无内参”是错的；真正要补的是**手眼外参/畸变/工具坐标**，不是内参。
2. **头部相机 fx 跨任务差异很大**：左目 `fx ≈ 186.0–296.1`；例如 OrganizeBookshelf/ZipUp/StackBowls 约 **186**，PackDoll/Unlock/ToolboxStorage 约 **296**，HangCup 约 **282.4**。所有图像都是 480×640，但相机模型/裁剪/标定不同。**不能全局用一套头部内参/射线**；必须按任务读 `meta/info.json`，在线用 `state_d435`/`lower_body` 恢复外参，并用腕部做局部兜底。
3. **`pivot` 不是常量**：`pivot_4` 在多数任务为 0.15，但 FoldTowel 约 0.120、StorePaddle 约 0.113、OrganizeTools 约 0.214；`height` 均值 0.727–0.740，但全局最低 **0.608**；`angle_z` 在多个任务可到 **±0.8**。这说明下身体/腰部在任务中会下蹲、转身、支撑，不是“站着不动”。**`pivot` 应作为任务/相位先验检索，而不是置零或写死 0.74。**
4. **动作标签领先状态**：对每个任务前 100 帧做 `action.*_arm[t]` vs `state.*_arm[t+lag]` 扫描，lag 中位数为 **3 帧（100ms）**；64 个“任务×手臂”组合里，42 个最佳 lag=3，11 个 lag=4，7 个 lag=2，2 个 lag=5，1 个 lag=7，1 个 lag=0。本地 HangCup/ZipUp shard 全 episode 扫描也是**左臂 lag=3、右臂 lag=2**。训练时若不做对齐，模型会学成“动作领先状态”，推理时表现为过冲/抖动。

其他审计结果：

- **夹爪**：`action.*_gripper` 实际 0–4.5；`observation.state.*_gripper` 约 -0.28–4.83；README 写 Dex1 5.5（开）→0（关）；线上 API 只写 `opening [1]`，未给范围。**必须先做尺度探测，不能假设 0–1 或 0–5.5。**
- **`recomputed_ee_valid`**：32 个任务全为 1.0，没有质量区分度，别拿它做过滤。
- **重复性**：本地 HangCup 719/719、ZipUp 369/369 episode 粗签名唯一；没有明显整段重复，但近重复很多，仍需多样性采样。
- **长尾**：HangCup 94–411 帧，中位 175；ZipUp 207–660，中位 344；长尾样本会主导均方误差，训练采样要按“有效动作段”而不是整段帧数。
- **编码域差**：训练视频 AV1 yuv420p；线上 `web_policy.py` 用 **JPEG q95、4:4:4** 传输。训练/推理的图像退化、色度、锐度不同，需 codec-matched 增强。

### 1.4 “干净数据是敌人”：数据质量 ≠ 平滑/成功/干净

本轮最重要的观念修正来自 Spirit-v1.5 的公开文章《Clean Data Is the Enemy of Great Robot Foundation Models》：

- 过度 curated 的数据会限制多样性，模型学不到恢复、遮挡、杂乱和失败重试；开放、非脚本、多样数据在相同数据量下迁移更好（文中报告收敛快 40%，采集效率 +200%）。
- 但另一条线（QoQ、RoboDrop、GiB、PSD 指标、GR-BC）又证明：**低质量样本/错位/犹豫/错误子任务会伤害后训练**，需要 curation。

两者不矛盾，关键在定义：

> **质量不是“轨迹平滑、一次成功、场景干净”，而是“这段数据对目标任务有因果贡献、且监督对齐”。**

所以 DQ-SCORE 不做好人/坏人二分，而做三件事：

1. **保留恢复段**：犹豫、重抓、失败后重试，是 RECOVERY-MEM 的原料；不要因为“不完美”全删。
2. **惩罚错位/污染**：动作-状态 lag、相机标定错、夹爪饱和、NaN/形状错误，是硬伤，必须降权/修正。
3. **按后果加权**：一段动作是否真的把任务目标推近（GR-BC 的 goal-potential reduction），比“看起来顺不顺”更重要。

这直接把“数据质量”从清洗工程变成了**记忆索引的排序函数**。

### 1.5 轮足机器人：G1-D 是干扰项；真正可用的是“双频执行”隐喻

- 挑战赛规则/数据是 **G1 系列人形**，`lower_body[15]`、`pivot[7]`、`height`；不是 G1-D。
- 宇树 **G1-D** 是带轮式底盘/升降柱的数据采集平台（官方页面明确“wheels and lifting mechanisms”，轮式差速、360° 原地转），适合采数据，不是本届挑战赛硬件。
- 所以“轮足机器人”不应驱动我们去设计轮式移动/底盘控制；它应驱动一个**控制频率隐喻**：
  - **WHEEL（轮式）**：自由空间、长距离、语义明确、少接触 → 长 chunk、全局 VLA + TASK-MEM、尽量少调用，争取步骤分/时间。
  - **LEG（足式）**：接触段、狭窄容差、扰动/滑移 → 短 chunk、局部视觉伺服 + CONTACT-MEM、每 3–5 步修正。
- 接口的 `control_space` 是**每个提交固定的 `joint` 或 `ee`**，不能动态切换；所以 router 切换的是 **chunk 长度、伺服增益、记忆作用域、重规划频率**，不是动作空间。
- 这与 SkipVLA 的“自由空间用经典规划、接触段才问 VLA”同构，但我们的“轮”和“足”都跑同一个 VLA，不引入第二个学习策略。

### 1.6 记忆检索：近期工作都在“把记忆学进模型”，我们做“把记忆放在控制器外”

近期代表性工作：

- **MemoryVLA**（ICLR 2026）：perceptual-cognitive memory bank，把低层感知和高层语义存进 bank，working memory 检索融合，再喂 diffusion action expert。
- **EchoVLA**（arXiv 2511.18112）：scene memory + episodic memory，面向移动操作。
- **EvoMem-VLA**（arXiv 2610.05418）：state-evolution memory，用 frame-pair delta token 记录“发生了什么变化”。
- **TemporalFlow-VLA**（arXiv 2608.26821）：用机器人状态/几何/标定相机构造 execution history，监督 temporal queries。
- **RA-VLA**（arXiv 2608.25585）：retrieval-augmented VLA 做 test-time adaptation，强调 behavior-aligned retrieval 和 behavioral inertia。
- **Harness VLA**（arXiv 2607.08448）：把 frozen VLA 当可重试的接触 primitive，外面用 memory-guided agent + 解析 primitive 组合。
- **ReWeight**（arXiv 2609.13851）：demonstration-level retrieval + sample-level weighting，把人类数据用于 VLA 后训练。
- **SkipVLA**（arXiv 2609.20648）：自由空间用经典规划，接触段才问 VLA。

它们的共同点是：**记忆要么被学进模型参数/额外模块，要么被放进一个 agent 循环**。这对本赛事有两个问题：

1. 单模型规则下，“再加一个学习记忆模块/第二个策略”合规风险高；
2. 远程 API 下，多一层模型/agent 会增加延迟和故障点。

DQ-MEM 的差异：

> **记忆是只读的数据结构，不是模型；检索只输出目标位姿、相位、stance、恢复片段和置信度，动作仍由同一个 WLA + 确定性伺服产生。**

这样既保留“测试时适应”，又不新增学习模型；记忆可以离线构建、随提交包分发、CPU 检索。

### 1.7 为什么现在能做

- 官方 **UnifoLM-WLA-1.0-Base**（6B）已开源，冻结 VLM、只训 DiT action head + state projector，单张 24GB GPU 可微调；默认 `chunk_size=30`、30fps、4 步扩散。
- 33k 条演示 + 四路 RGB + 头部双目 + 腕部内参 + `lower_body` + `pivot`，足够构建任务/接触/恢复记忆。
- 第 10 轮 FACT-VLA 给了相位/子任务分解；第 11 轮 GEO-RESIDUAL 给了接触距离/滑移/编辑检测；第 12 轮 CHUNK-SERVO 给了 30 步规划 + 5 步伺服 + 相对目标。DQ-MEM 是在它们之上加“质量门控”和“stance/恢复记忆”，不是从零开始。

## 2. 诊断：三个缺口叠在一起

### 2.1 数据缺口：169 小时不等于 169 小时有效监督

- **时间错位**：动作领先状态 ~3 帧；接触段 100ms 就是几毫米。
- **空间错位**：头相机 fx 跨任务 186–296；用一套内参做几何/深度会系统性偏。
- **尺度错位**：夹爪动作 0–4.5、状态 -0.28–4.83、README 5.5→0；不统一就会“以为在张开，其实在夹紧”。
- **姿态错位**：pivot/height 任务相关；置零会丢掉下蹲/转身/支撑。
- **域错位**：AV1 vs JPEG q95；颜色/锐度/压缩噪声不同。
- **样本错位**：长尾、犹豫、重抓、近重复；等权混训会让“长而差”的段主导。

这些都不是“模型不够大”，而是“监督信号不够对”。DQ-SCORE 先修这个。

### 2.2 记忆缺口：VLA 在每个 chunk 之间是“失忆”的

- 每次 `get_action` 只看到当前观测（以及声明的历史栈）；chunk 内不再看世界。
- 33k 演示包含大量“同一任务、不同位置/背景/干扰”的成功与恢复经验，但推理时完全不可查。
- 一个 6B VLA 不可能把 33k 条的所有任务特定细节都压进权重；检索可以把“任务级先验”外置，降低对模型容量的要求。
- 记忆最有价值的不是“复制动作”，而是：
  - **目标**：夹爪相对目标/受器的成功位姿；
  - **相位**：现在该接近、接触、插入、释放还是恢复；
  - **stance**：下身体高度/腰部/pivot；
  - **预算**：这类任务通常多少步成功（步骤分）；
  - **恢复**：失败后往哪退、怎么重抓。

### 2.3 执行缺口：接触段需要“足式”，自由空间需要“轮式”

- 自由空间：语义/路径明确，长 chunk 省调用、省时间、步骤分更稳。
- 接触段：需要高频看腕部、短 chunk、低增益、法向缩幅；长 chunk 会把小误差放大。
- 固定 5 步伺服不是最优：自由空间浪费时间，接触段仍可能不够快；固定 30 步更危险。
- WHEEL-LEG ROUTER 用相位/接触距离/检索 margin/扰动信号选择频率，把“轮足”变成“双频”。

### 2.4 为什么头部模型仍然不到 30%

- 它们优化的是“语义泛化/未来预测/多 embodiment”，不是“最后 3 厘米的接触控制”。
- 它们没有把 33k 演示变成测试时可查的先验；训练完就“忘了”。
- 它们没有修数据错位；错位在训练时是噪声，在推理时是系统性偏差。
- 它们没有任务特定 stance；站立 G1 的下身体不是常量。
- 所以，**在一个所有模型都共享的执行/数据瓶颈上，做数据质量 + 记忆 + 双频，比换更大模型更可能有边际收益。**

## 3. 方法：DQ-MEM + WHEEL-LEG ROUTER

### 3.1 总架构

```text
┌──────────────────────────────────────────────────────────────┐
│ Evaluator (N ports 8765..8765+N-1)                           │
└──────────────────────────┬───────────────────────────────────┘
                           │ obs / action chunk (websocket+msgpack)
                           ▼
┌──────────────────────────────────────────────────────────────┐
│ Per-port PolicyService (CPU, state isolated)                 │
│  ├─ DQ-MEM retriever (task/contact/recovery, read-only)      │
│  ├─ WHEEL-LEG router (phase/contact/margin/edit)             │
│  ├─ deterministic servo (PBVS/IBVS, 3–5 step)                │
│  ├─ plan cache (30-step WLA plan, async)                     │
│  └─ adapter (WLA 54D -> challenge 21D, pivot/height/gripper) │
└──────────────────────────┬───────────────────────────────────┘
                           │ async, batched
                           ▼
┌──────────────────────────────────────────────────────────────┐
│ Shared WLA server (GPU, one model, N sessions)               │
│  UnifoLM-WLA-1.0 / Base, 30-step, 30fps, 4-step diffusion    │
└──────────────────────────────────────────────────────────────┘
```

- 每个端口独立 `reset()`、独立记忆 query 状态、独立 plan cache；共享模型权重只有一份。
- 记忆检索/伺服是 CPU 线程；VLA 异步；`get_action` 永远不因检索/伺服失败而返回非法动作。
- 记忆索引只读；不在评测中更新权重/索引，避免“在线学习”合规争议。

### 3.2 DQ-SCORE：质量分不是清洗分

对每个 episode/片段 `i` 定义：

```math
q_i = \sigma\left(
  w_a q^{align}_i +
  w_c q^{calib}_i +
  w_g q^{consequence}_i +
  w_v q^{coverage}_i +
  w_s q^{smooth}_i +
  w_l q^{label}_i
\right)
```

各项含义：

| 项 | 怎么算 | 作用 |
|---|---|---|
| `q_align` | 用 per-task lag 把 action 与 state 对齐后，残差/速度一致性；lag 由互相关估计 | 惩罚动作-状态错位；对齐后的样本才能学“因果” |
| `q_calib` | 头部/腕部重投影误差、fx 与任务中位数偏差、双目视差有效像素比例 | 惩罚相机标定异常；fx 186/296 的任务要单独建模 |
| `q_consequence` | GR-BC 风格：该片段把“到目标的剩余步数/势能”降低了多少；成功终点 + 相位进度 | 保留“真正推进任务”的段，而不是“看起来顺”的段 |
| `q_coverage` | 任务内位姿/物体/背景/相位的 k-center 覆盖或熵 | 防止少数简单场景主导；位置/背景泛化靠它 |
| `q_smooth` | 加速度/ jerk / PSD 高频能量；但只在“非恢复段”惩罚 | 抑制抖动/犹豫；恢复段不惩罚，保留 |
| `q_label` | 语言/相位标签是否重复、错标；可用离线 VLM 重标注或规则校验 | 提升指令/相位监督质量；不引入在线第二模型 |

硬门（直接降权/剔除）：NaN/Inf、形状错误、缺相机、夹爪长时间饱和、动作超限、`recomputed_ee_valid=0`（本数据全 1，留作未来）。

关键：**`q_smooth` 不能单独决定去留**。恢复段可能高 jerk，但它是 RECOVERY-MEM 的宝贵原料；`q_consequence` 和 `q_coverage` 优先。

用途：

1. **WLA action-head 微调采样权重**：`p_i ∝ q_i`（按任务分层，避免大任务主导）。
2. **记忆入库优先级**：低质量片段不进 CONTACT-MEM，但恢复段可进 RECOVERY-MEM。
3. **任务选择**：`q_task` 低的任务（标定差/错位重）先修数据，不急着堆工程。

### 3.3 三层记忆

#### TASK-MEM（任务级，全局）

```text
TaskMemory:
  task_id, language
  anchor_set            # 目标/受器的相对锚点，如杯架标记、网口、试管架
  phase_graph           # 阶段顺序/分支：approach -> align -> contact -> insert -> release
  pivot_profile[7]      # 任务的 pivot 中位/分位，尤其 pivot_4、height、angle_z
  height_profile        # 按相位的高度曲线（常量或分段）
  step_budget           # 成功演示的步数中位/分位
  object_set            # 水果/积木/工具/文具等类别
  failure_modes         # 滑动/遮挡/错位/掉落/人为干扰
```

作用：给 VLA/伺服一个“这个任务的全局先验”；位置泛化时只更新 anchor，不重训。

#### CONTACT-MEM（接触级，局部）

```text
ContactMemory:
  task_id, phase
  episode_id, frame_idx
  quality
  T_anchor_ee[6]        # 从成功演示反推：受器/目标 -> 夹爪 的相对目标
  wrist_goal            # 腕部目标图（128x128 JPEG/ORB/颜色/轮廓）
  insertion_axis        # 插入/挂/叠的方向
  gripper_aperture      # 接触前/接触时的夹爪开度
  expected_steps        # 从该关键帧到成功的剩余步数
  source                # 数据集/任务/片段
```

作用：接触段的目标不是“绝对图像”，而是“当前受器/目标 + 成功相对位姿”；这样位置/背景/干扰物变化时仍可用。

#### RECOVERY-MEM（恢复级，episodic）

```text
RecoveryMemory:
  task_id, failure_signature   # 滑移/未夹住/目标被移动/遮挡/人为干扰
  pre_state, pre_wrist
  recovery_segment             # 退出 -> 重定位 -> 重抓/重规划 的短片段
  quality
```

来源：成功演示中的犹豫/重抓/失败后重试段，以及单任务测试通道的失败日志（如果允许）。作用：人为干扰/位置泛化时，先检索“类似失败怎么退”，而不是让 VLA 从零重规划。

### 3.4 离线构建管线

```text
for each task:
    read meta/info.json -> camera params, fps, episodes
    for each episode:
        align action/state by per-task lag
        transcode/hold AV1 + JPEG q95 variants
        segment phases (contact detection + action/state + offline labels)
        compute DQ-SCORE
        if quality >= gate:
            add TASK-MEM anchors/pivot/height/step budget
            add CONTACT-MEM pre-contact keyframes
        if recovery segment:
            add RECOVERY-MEM
    build index (FAISS/HNSW or numpy) + metadata
```

相位切分不需要在线第二个模型：

- 规则信号：夹爪开度变化、EE 速度/加速度、腕部目标出现、接触距离 `d_t`（第 11 轮）、物体运动残差 `r_grasp`；
- 离线语言/子任务标签可以用官方 WLA 的子任务输出或离线 VLM 重标注；**只用于数据标注，不进入在线推理**；
- 若合规严格，完全用规则 + 人工抽检，避免任何额外模型。

### 3.5 在线检索

```text
query = (task_id/language, phase_estimate,
         current head/wrist images, EE pose, lower_body,
         remaining_time, failure_signature?)

# stage 1: task/language filter
# stage 2: phase/contact filter
# stage 3: pose/visual rerank (ORB/color/contour or same-VLA encoder)
topk = top_k(query, k=5)
goal = rerank(topk, pose_consistency, image_quality, quality, step_efficiency)
```

输出：

```text
goal_pose_relative   # CONTACT-MEM
wrist_goal           # CONTACT-MEM
pivot_profile        # TASK-MEM
height_profile       # TASK-MEM
phase                # TASK-MEM
expected_steps       # TASK-MEM/CONTACT-MEM
recovery_hint        # RECOVERY-MEM
confidence           # retrieval margin + pose consistency + image quality
```

置信度：

```math
c = \alpha \cdot \text{margin}(d_1,d_2) + \beta \cdot \text{pose\_consistency} + \gamma \cdot \text{image\_quality}
```

- `margin = (d_2 - d_1)/(d_2 + eps)`：top-1 与 top-2 的差距；差距小说明近邻歧义，降置信度。
- 置信度低 → 不硬用记忆；回退 VLA/粗对齐；或在 LEG 模式慢速重试。

### 3.6 WHEEL-LEG ROUTER

| 模式 | 触发 | chunk | 记忆 | 控制 | 目的 |
|---|---|---:|---|---|---|
| **WHEEL** | 自由空间、远离接触、相位=approach/transport、检索 margin 高 | 15–30 | TASK-MEM | VLA 前馈为主，低增益/不伺服 | 快、省调用、保步骤分 |
| **PRE_CONTACT** | 距接触 <5cm 或腕部目标进入视野 | 8–10 | TASK-MEM + CONTACT-MEM top-k | PBVS 粗对齐，降速 | 过渡，避免突然切太慢 |
| **LEG** | 接触/插入/挂/叠/拉链/锁/拧盖；`d_t < d_c` | 3–5 | CONTACT-MEM + TASK-MEM | PBVS/IBVS 混合，法向缩幅 | 最后 3 厘米闭环 |
| **RECOVER** | `edit_score` 高、滑移、抓空、目标被移动、检索 margin 低 | 3 | RECOVERY-MEM | 停 → 退 → 重定位 → 重抓/重规划 | 人为干扰/失败恢复 |

切换信号：

- `d_t`：夹爪到局部表面的米制距离（第 11 轮）；
- `phase`：TASK-MEM 相位分类 + 夹爪开度/EE 速度；
- `margin`：检索置信度；
- `edit_score`：场景被外力改变（第 11 轮）；
- `r_grasp` 突变：滑移；
- `RTT`：高延迟时提高 chunk、降增益，避免高频振荡；
- `remaining_time`：180s 预算，后段更保守。

注意：`control_space` 固定，router 只改 **chunk 长度/伺服增益/记忆作用域/重规划频率**；不切换 joint/ee。

### 3.7 与 CHUNK-SERVO 的保留、升级、剪枝

| 第 12 轮 | 本轮处理 | 原因 |
|---|---|---|
| 30 步 VLA 规划 + 5 步伺服 | **保留**，但 5 步改为 router 的 3/5/8/15/30 | 自由空间不需要 5 步；接触段可能需要 3 步 |
| DG-KEYFRAME 演示检索 | **升级为 CONTACT-MEM + TASK-MEM** | 加质量分、stance、恢复、步数预算 |
| 相对目标 `T_target_ee*` | **保留** | 位置/背景/干扰泛化的关键 |
| 数字孪生标定 RTT/增益/外参 | **保留，优先级降低** | 先把真实数据对齐/标定做好，再谈孪生 |
| `pivot` 置零/常量 | **剪枝** | 数据证明 pivot/height 任务相关；改为 TASK-MEM 检索 |
| “腕部无内参” | **剪枝/纠错** | 腕部有内参；补手眼外参 |
| “干净数据=好数据” | **剪枝** | 保留恢复/多样段；质量=后果+覆盖+对齐 |
| “G1-D 轮足” | **剪枝** | 挑战赛是 G1 人形；轮足只作双频隐喻 |
| 榜单名次当难度表 | **剪枝** | 预览数据，不作为任务选择依据 |

### 3.8 WLA adapter 的修正（54D → 挑战赛 21D）

- WLA：`left_ee_rel[6], left_gripper[1], left_hand[6], right_ee_rel[6], right_gripper[1], right_hand[6], waist[3], torso[3], base_vxvy[2], base_wz[1], base_pose_rel[6], height[1], left_leg[6], right_leg[6]`。
- 挑战赛 `ee`：`left_ee_abs[6], right_ee_abs[6], left_gripper[1], right_gripper[1], pivot[7]`。
- 映射：
  1. `left_ee_abs = compose(T_base_ee_current, exp(left_ee_rel))`，转 xyz+rpy；右臂同理；**整段 30 步先 compose 成 base 系绝对目标，再切片**，不能切片后各自以不同锚点解释。
  2. 夹爪：用挑战赛/数据实测范围归一化；先做单任务探测，确认方向/尺度。
  3. `pivot`：`[0,0,0, 0, pivot4_task, 0, height_task]` 起步；`pivot4_task`/`height_task` 来自 TASK-MEM；`vx/vy/angle_z` 在站立桌面任务先置 0，若单任务通道证明有收益再放开。
  4. `height`：常量任务（如 PourOutMedicine 0.740）用常量；变化任务（如 PickOutBatteries 最低 0.608）用相位 profile。
  5. 腿部/灵巧手：挑战赛 `ee` 不直接下发；WLA 的腿/手只作为辅助损失或屏蔽。
- **不要猜 pivot 语义**：README 只写“Lower-body / pivot target”；先用单任务通道做小步测试（pivot 全零 vs 检索值），确认符号/单位/安全范围。

### 3.9 合规边界

- **一个模型**：只提交一个 WLA checkpoint；DQ-MEM 是数据/索引，不是第二个策略。
- **检索特征**：默认用 ORB/颜色/轮廓/几何（非学习模型）；若用视觉编码器，优先用**同一个 WLA 的 encoder**；用第三方编码器前先问官方。
- **不进行在线学习**：评测中不更新权重/索引；只读记忆。
- **可复现**：记忆构建脚本、质量分、索引、版本号随提交包记录；每个端口状态隔离。
- **安全回退**：任何检索/伺服异常 → 返回上一组合法 chunk 或安全 hold；绝不返回 NaN/错误形状。

## 4. 竞赛策略：先修数据，再加记忆，最后才开 router

### 4.1 任务优先级

```text
priority_t = q_task_t * Δ_contact_t * Δ_memory_t / cost_t
```

- `q_task_t`：数据质量（对齐/标定/夹爪/长度/覆盖）；
- `Δ_contact_t`：接触段失败占比（语义先验，单任务通道更新）；
- `Δ_memory_t`：记忆预期增益（有稳定腕部视野、任务特定 stance、可检索恢复段）；
- `cost_t`：工程/评测成本（长任务、标定难、目标难检）。

先验分档（**不是榜单排名**）：

- **A 档（先做）**：HangCup、DisconnectEthernet、PlugCharger、Unlock、ArrangeTestTubes、ZipUp、PlugInEthernet、StackBowls、ToolboxStorage、PourOutMedicine。
- **B 档（第二批）**：PackDoll、OrganizeStationery、PackBag、PackPhone、OrganizePencilCase、StorePaddle、StoreEarphones。
- **C 档（观察/低投入）**：FoldTowel、ConveyorSorting、SpellRobot、FruitSorting、ColorArrangement（变形/动态/语义主导，记忆增益低）。

风险标记：头部 fx 186 的 OrganizeBookshelf/ZipUp/StackBowls 要先修标定；PickOutBatteries 高度最低 0.608，要 stance profile；OrganizeTools `pivot_4=0.214`、StorePaddle `0.113`，要单独建 TASK-MEM。

### 4.2 单任务通道协议

每个候选任务至少测：

| 项 | 目的 |
|---|---|
| 基线：官方 WLA + 全零/常量 pivot，H=30 | 真实基线，不用榜单 |
| + lag 对齐 + 相机标定 + 夹爪尺度 + codec 增强 | 修数据错位，确认可复现 |
| + DQ 加权微调 | 质量分是否真的涨点 |
| + TASK-MEM/CONTACT-MEM | 记忆是否真的涨点 |
| + WHEEL-LEG router | 双频是否优于固定 5/30 |
| 记录：成功率、步骤分、time-to-contact、失败相位、pivot 实际值、夹爪范围、RTT | 更新 `q_task/Δ/cost` |

统计：单任务 10 次官方 trial 噪声很大；测试通道尽量 30–50 次，报告配对差值的 bootstrap 置信区间。A/B 必须同初始条件/同任务族，避免把任务难度差当方法增益。

### 4.3 提交节奏

1. **安全基线**：WLA + adapter + 合法 pivot（先常量/全零），锁端口/token/超时；若允许多次提交，先交安全基线锁 tie-break。
2. **数据修正版**：lag 对齐 + per-task 标定 + 夹爪尺度 + codec 增强；H=30。
3. **DQ 微调版**：action-head 质量加权；H=30。
4. **记忆版**：TASK-MEM + CONTACT-MEM；H=5–10；pivot/height 检索。
5. **router 版**：WHEEL-LEG；保留回滚开关。
6. **全量 320 trials**：只在单任务通道过门后跑；不要用正式提交做探索。

## 6. 风险与诚实边界

1. **榜单是预览**：不能用 29.7% 证明 SOTA，也不能用任务排名选任务；所有增益以单任务通道为准。
2. **记忆可能过拟合训练场景**：用相对位姿/anchor，不用绝对图像；位置/背景变化时重估 anchor；低 margin 回退。
3. **pivot 语义未知**：README 只写“Lower-body / pivot target”；先小步探测，别猜符号/单位。
4. **夹爪尺度未知**：线上范围未写；先探测方向/范围；错误尺度会直接抓空/夹坏。
5. **动作-状态 lag 是估计**：用互相关 + 全 shard 复核；不同任务/手臂可能不同；按任务对齐。
6. **相机标定差异大**：头 fx 186–296；不能全局一套；按任务读 meta，在线用 state_d435/lower_body，腕部兜底。
7. **单模型合规**：记忆是数据；检索默认非学习特征；第三方编码器先问官方。
8. **延迟/并发**：N 端口共享 GPU；记忆检索 CPU 轻量；VLA 异步；p99 延迟要测。
9. **安全**：任何异常返回上一组合法动作/安全 hold；不返回 NaN/错误形状；接触段力不可测，只能保守。
10. **不要重蹈“更大模型”**：本轮的边际收益来自数据对齐、记忆、stance 和双频，不是参数量。

## 0. 摘要

本报告回答四个问题：

1. **榜单头部方案做了什么、瓶颈在哪？**
   8 个条目都在提升语义/场景泛化（3D 推理、世界模型、多 embodiment、开放世界 co-training），但多数仍是 chunk 内开环；共同缺少测试时记忆、任务特定 stance/接触先验。榜首 29.7% 还是脚本生成的预览值，不是真机 SOTA。

2. **33k 条演示能不能直接用？**
   不能等权直接用。32 个 HF 数据集合计 **33,276 episodes / 18,282,246 frames / 169.28 h**；动作标签普遍领先状态约 **3 帧（100ms）**，头部相机 fx 跨任务 **186.0–296.1**，夹爪动作 0–4.5 而 README 写 5.5→0，训练视频 AV1 而线上 JPEG q95。数据错位不修，模型越大越会放大偏差。

3. **本轮创新是什么？**
   **DQ-MEM**：用 DQ-SCORE 给演示/片段打“可用性”分；把高质量片段做成三层只读记忆；推理时只输出目标位姿、相位、stance、步数预算和恢复提示，动作仍由同一个官方 WLA + 确定性伺服产生。**WHEEL-LEG ROUTER** 在自由空间跑长 chunk，在接触段跑短 chunk，不切换 `control_space`。

4. **怎么验证？**
   G0–G8：先修数据（lag/标定/夹爪/编码），再做质量加权微调，再加记忆，最后开 router；所有增益以单任务测试通道的配对实验为准，不拿榜单预览当证据。

## 1. 赛事与接口事实

### 1.1 赛道/规则/评分

- 32 个桌面任务，一个通才模型完成全部任务；每任务 10 次 trial。
- 泛化类型 5 类 × 2 次：位置、干扰物、背景、未见物品、人为干扰。
- 单次上限 **180 s**。
- 排名：先平均成功率，再平均步骤分，再更早提交。
- 评测跨 N 台机器人，端口从 **8765** 连续；有**不计分单任务测试通道**。
- `challenges.html` 标每任务步骤分满分 100；手册另称 94 个评分步骤（以手册为准）。
- 难度分组：Easy 12 / Medium 12 / Hard 8。

### 1.2 观测/动作/控制

| 项 | 内容 |
|---|---|
| 图像 | 4 路 RGB 480×640：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` |
| 双臂关节 | `[7]` |
| EE 位姿 | `[6]`，xyz + rpy，base 系 |
| 夹爪 | `[1]` |
| 下身体 | `lower_body[15]` |
| 语言 | `str` |
| 控制空间 | `control_space` 仅 `"joint"` 或 `"ee"`，**每个提交固定且互斥** |
| 动作 chunk | `action_chunk_size` 固定 |

| 鉴权 | 每次 `get_action` 带 `meta.token` |


`action.base_command[4]`：

```text
vx, vy, angle_z, height
```

### 1.3 提交/并发/合规

- 一个提交固定一个模型/一套权重；不能按任务切换 checkpoint。
- 每个端口独立 `reset()`；共享 GPU 模型，状态/缓存按端口隔离。
- 允许的工程手段：异步推理、chunk 缓存、确定性伺服、CPU 检索、图像预处理。
- 不允许/高风险：多模型 ensemble、按任务动态加载不同权重、在线更新权重/索引、未申报的第二个学习策略。

### 2.4 pivot / height / lower_body

- `pivot_4` 不是常量：多数 0.150，FoldTowel≈0.120，StorePaddle≈0.113，OrganizeTools≈0.214。
- `height` 均值 0.727–0.740，但全局最低 **0.608**（PickOutBatteries）；部分任务高度恒定（PourOutMedicine/StoreCups/StoreEarphones 0.740），部分任务波动大（HangCup 0.654–0.740，PickOutBatteries 0.608–0.740）。
- `angle_z` 在多个任务可到 **-0.8～+0.8**；下身体会下蹲、转身、支撑。
- 结论：**pivot/height 是任务/相位先验，不是常量**；应进 TASK-MEM，而不是全零。

### 2.5 动作-状态滞后

- 对每个任务前 100 帧做 `action.*_arm[t]` vs `state.*_arm[t+lag]` 扫描；64 个“任务×手臂”组合：
  - lag=3：42 个；
  - lag=4：11 个；
  - lag=2：7 个；
  - lag=5：2 个；
  - lag=7：1 个（T05 左臂）；
  - lag=0：1 个（T25 左臂）。
- 中位数 **3 帧 = 100 ms**。
- 本地 HangCup shard（719 episodes）与 ZipUp shard（369 episodes）全 episode 扫描：左臂 3、右臂 2。
- 训练：把 action 向后移 `lag` 帧，或把 state 向前移；不要全局固定 3，按任务/手臂扫。
- 本地 parquet 是 **shard**，不是全量：HangCup 130,565 行 / 719 episodes；ZipUp 131,972 行 / 369 episodes。

### 2.6 夹爪、重复性、其他

- `action.left/right_gripper`：**0–4.5**；`observation.state.left/right_gripper`：**-0.28–4.83**。
- README：Dex1 **5.5（开）→0（关）**；线上 API 只写 `opening [1]`，未给范围。
- `recomputed_ee_valid`：32 任务全 1.0，无区分度。
- 本地 shard episode 粗签名唯一；没有明显整段重复，但近重复多，需多样性采样。
- 训练视频 AV1 yuv420p；线上 JPEG q95/4:4:4；存在压缩/色度/锐度域差。
- 长尾：HangCup 94–411 帧（中位 175）；ZipUp 207–660（中位 344）；按有效动作段采样，不按总帧数。

### 2.7 数据审计对方案的直接约束

1. **必须做 per-task/per-arm lag 对齐**，否则学的是错位动作。
2. **必须做 per-task 相机模型**，不能全局一套 fx。
3. **必须做夹爪尺度探测**，不能假设 0–1。
4. **pivot/height 必须任务化**，不能零/常量。
5. **必须做 codec-matched 增强**，否则线上掉点。
6. **质量分必须保留恢复/多样段**，不能只留平滑成功段。

|---|---|---|
| MemoryVLA（ICLR 2026） | perceptual-cognitive memory bank + working memory 检索融合 + diffusion action expert | 记忆学进模型/模块；DQ-MEM 只读外挂，不改权重 |

### 4.2 数据质量

| 工作 | 核心 | 对 DQ-MEM 的启发 |
|---|---|---|
| Spirit-v1.5（blog） | “Clean Data Is the Enemy”：多样/非脚本数据优于过度 curated | 不删恢复/多样段；质量≠干净 |
| QoQ（2603.09056） | 质量=对验证损失的贡献，不是人工偏好 | `q_consequence` 优先于 `q_smooth` |
| RoboDrop（2609.10021） | 用局部梯度兼容性检测有害样本 | 质量分可用于采样权重/剔除 |
| GiB（2605.01529） | 丢弃错误子任务，保留好子任务 | 片段级质量，不整集丢弃 |
| PSD（2605.01544） | 用平滑度等指标排序演示 | 平滑只是弱先验，不能单独用 |
| GR-BC（2610.20504） | 按 goal-potential reduction 加权 chunk | `q_consequence` 的直接依据 |

**DQ-SCORE 的立场**：质量 = **后果贡献 × 覆盖度 × 监督对齐**；平滑/成功只是其中一小项。

### 4.3 轮足/双频

- G1-D 是轮式+升降的数据采集平台，不是挑战赛硬件；不能设计轮式底盘。
- SkipVLA 证明“自由空间经典规划 + 接触段 VLA”有效；DQ-MEM 把“轮/足”抽象为**频率/记忆作用域**，不是底盘。
- 接口 `control_space` 固定；router 只改 chunk/增益/重规划频率，符合规则。

## 5. DQ-MEM 设计

### 5.1 架构

```text
Evaluator ports 8765..8765+N-1
        │ obs/action (websocket+msgpack)
        ▼
Per-port PolicyService (CPU)
  ├─ DQ-MEM retriever (read-only)
  ├─ WHEEL-LEG router
  ├─ deterministic servo
  ├─ plan cache (30-step WLA)
  └─ adapter (54D→21D, pivot/gripper)
        │ async batch
        ▼
Shared WLA server (GPU, one model)
  UnifoLM-WLA-1.0 / Base, chunk=30, 30fps, 4-step diffusion
```

- 每端口独立 `reset()`、独立 query 状态、独立缓存。
- 检索/伺服 CPU 线程；VLA 异步；`get_action` 不因检索失败而返回非法动作。
- 记忆只读；评测中不更新。

### 5.2 DQ-SCORE

对 episode/片段 `i`：

```math
q_i = \sigma\left(
  w_a q^{align}_i +
  w_c q^{calib}_i +
  w_g q^{consequence}_i +
  w_v q^{coverage}_i +
  w_s q^{smooth}_i +
  w_l q^{label}_i
\right)
```

| 项 | 计算 | 默认权重 | 说明 |
|---|---|---:|---|
| `q_align` | 用 per-task/per-arm lag 对齐后，action 与 state 的归一化残差/速度一致性；`exp(-e/τ)` | 1.0 | T05 左臂 lag=7、T25 左臂 lag=0，必须单独处理 |
| `q_calib` | 头部 fx 与任务簇中位数偏差、双目有效视差比例、腕部重投影误差 | 0.8 | fx 186/296 的任务单独建模 |
| `q_consequence` | `Φ(s_end)-Φ(s_start)` 或片段目标势能下降；`Φ` 用 TASK-MEM anchor 到 EE 的距离/相位进度 | 1.2 | 不是“平滑”，是“推进任务” |
| `q_coverage` | 位姿/物体/背景/相位的 k-center 覆盖或熵 | 0.8 | 保位置/背景泛化 |
| `q_smooth` | 非恢复段的 jerk/加速度/高频能量 | 0.3 | 恢复段不惩罚 |
| `q_label` | 语言/相位标签一致性、重复/歧义 | 0.5 | 可用离线规则/VLM 重标注 |

硬门：

- NaN/Inf、形状错误、缺相机、动作超限、夹爪长时间饱和、`recomputed_ee_valid=0`（本数据全 1）。
- 硬门样本 `q=0`，但不整集丢弃；按片段处理。

采样：

```math
p_i = \frac{(0.2 + 0.8 q_i)^\beta}{\sum_j (0.2 + 0.8 q_j)^\beta}, \quad \beta=0.5
```

- 保留至少 30% 的每任务样本，防止质量分把多样性洗掉。
- 恢复段：`q >= 0.3` 且 `q_consequence` 高即可进 RECOVERY-MEM；不要用 `q_smooth` 一票否决。

### 5.4 离线构建

```python
for task in tasks:
    info = load_json(meta/info.json)
    lag = estimate_lag(task)                 # per-arm, full shard
    for ep in episodes:
        frames = load_episode(ep)            # sample keyframes, don't decode all
        a, s = load_action_state(ep)
        a_aligned = shift(a, -lag)           # action[t] <-> state[t+lag]
        phases = segment_phases(a_aligned, s, frames, info)
        for seg in phases:
            q = dq_score(seg, info, lag)
            if q >= TASK_GATE:
                update_task_mem(task, seg, q)
            if seg.phase in ("precontact", "contact") and q >= CONTACT_GATE:
                add_contact_mem(task, seg, q)
            if is_recovery(seg):
                add_recovery_mem(task, seg, q)
    build_index(task, dedup=True, diversity=True)
```

要点：

- 相位切分优先用规则信号：夹爪开度、EE 速度/加速度、接触距离、物体运动残差、腕部目标出现。
- 离线语言/相位重标注可用 WLA 子任务输出或离线 VLM；**只用于数据，不进入在线推理**。
- 合规严格时，完全用规则 + 人工抽检。

### 5.5 在线检索伪代码

```python
def retrieve(obs, task_id, phase, k=5):
    cand = task_index[task_id]
    cand = [c for c in cand if phase_compatible(c.phase, phase)]
    q_feat = visual_feature(obs.wrist)      # ORB/color/contour
    scored = []
    for c in cand:
        d_pose = pose_distance(obs.ee, c.T_anchor_ee)
        d_vis = visual_distance(q_feat, c.visual)
        d_q = 1.0 - c.quality
        d_steps = c.expected_steps / max(1, obs.remaining_steps)
        score = 0.45*d_pose + 0.30*d_vis + 0.15*d_q + 0.10*d_steps
        scored.append((score, c))
    top = nsmallest(scored, k)
    margin = margin_of(top)
    if margin < MARGIN_MIN:
        return MemoryResult(confidence=margin, fallback="vla_coarse")
    return fuse(top, confidence=margin)
```

输出：

```text
goal_pose_relative   # CONTACT-MEM
wrist_goal           # CONTACT-MEM
pivot_profile        # TASK-MEM
height_profile       # TASK-MEM
phase                # TASK-MEM
expected_steps       # TASK-MEM/CONTACT-MEM
recovery_hint        # RECOVERY-MEM
confidence           # margin + pose consistency + image quality
```

置信度：

```math
c = 0.45 \cdot \text{margin} + 0.35 \cdot \text{pose\_consistency} + 0.20 \cdot \text{image\_quality}
```

- `margin = (d_2 - d_1)/(d_2 + eps)`；
- `c < 0.35`：不硬用记忆；回退 VLA 粗对齐或 LEG 慢速重试；
- `c > 0.6`：可用目标位姿/腕部目标；
- `c` 只影响伺服增益/是否使用，不直接影响动作合法性。

### 5.6 质量门与回退

| 情况 | 动作 |
|---|---|
| 检索 top-1 质量 <0.5 | 降权/不用；只用 TASK-MEM 相位/stance |
| margin <0.15 | 视为歧义；回退 VLA 粗对齐 |
| 目标 anchor 不可见/被遮挡 | 用腕部目标/几何；仍不行则 RECOVER |
| pivot/height 未验证 | 用任务中位数，不放开大幅变化 |
| 夹爪尺度未确认 | 用保守开度，先探测 |
| 记忆索引缺失/损坏 | 直接回退纯 WLA；不阻塞 |

### 6.1 状态机

```text
   WHEEL ───────────────────────────────► PRE_CONTACT

     │ release/retreat                        │ d_t < 2cm / contact phase

     │                                       LEG

     └──────────── recovery done ◄──────── RECOVER
```

### 6.2 模式与参数

| 模式 | 触发 | chunk | 记忆 | 控制 | 目的 |
|---|---|---:|---|---|---|
| WHEEL | 自由空间/远离接触/phase=approach/transport/margin 高 | 15–30 | TASK-MEM | VLA 前馈，低增益，不逐帧伺服 | 快、省调用、保步骤分 |
| PRE_CONTACT | d_t<5cm 或腕部目标进入视野 | 8–10 | TASK-MEM+CONTACT-MEM top-k | PBVS 粗对齐，降速 | 平滑过渡 |
| LEG | 接触/插入/挂/叠/拉链/锁/拧盖；d_t<d_c | 3–5 | CONTACT-MEM+TASK-MEM | PBVS/IBVS，法向缩幅 | 最后 3 厘米闭环 |
| RECOVER | edit_score 高/滑移/抓空/目标移动/margin 低 | 3 | RECOVERY-MEM | 停→退→重定位→重抓/重规划 | 扰动/失败恢复 |

默认阈值（需单任务通道校准）：

```text
d_pre = 0.05 m
d_contact = 0.02 m
margin_min = 0.15
edit_tau = 0.25
slip_tau = 0.02 m/frame
cooldown = 150 ms
hysteresis = 2 frames
```

### 6.3 迟滞与防抖

- 模式切换需连续 2 帧满足条件；切换后 150ms 冷却。
- `LEG→WHEEL` 只在释放/后退且 `d_t>d_pre` 时；避免接触段来回切。
- `RECOVER` 超时 2s 或恢复片段完成 → 回 `PRE_CONTACT`；连续失败 3 次 → 保守 hold/重规划。
- RTT 高：增大 chunk、降增益；RTT 低：可缩短 LEG chunk。

### 6.4 伺服

- PBVS：`e = log(T_target_cur)`；位置 clamp（如每步 1–2cm）、旋转 clamp（如每步 3–5°）。
- IBVS 兜底：腕部目标点/轮廓误差，法向缩幅。
- 夹爪：接近时预开，接触时闭合/保持；用动作范围 0–4.5，先探测。
- 无力传感器：用 EE 误差、视觉残差、夹爪位置/电流（若有）做滑移代理；没有就保守。
- 安全：workspace bounds、max delta、timeout、非法动作过滤、上一组合法 chunk 回退。

## 7. WLA adapter（54D → 挑战赛 21D）

### 7.1 维度

WLA 动作 54D：

```text
left_ee_rel[6], left_gripper[1], left_hand[6],
right_ee_rel[6], right_gripper[1], right_hand[6],
waist[3], torso[3], base_vxvy[2], base_wz[1],
base_pose_rel[6], height[1], left_leg[6], right_leg[6]
```

合计：13+13+3+3+3+6+1+6+6 = 54。

挑战赛 `ee` 21D：

```text
left_ee_abs[6], right_ee_abs[6], left_gripper[1], right_gripper[1], pivot[7]
```

### 7.2 映射

1. **EE 相对→绝对**：先确认 WLA `*_ee_rel` 的锚点（当前 EE / 上一帧 / torso）。若是相对当前 EE：
   ```text
   T_abs_t = T_base_ee_current @ exp(se3(rel_t))
   ```
   若是 delta，则逐帧积分；若是绝对，直接透传。**整段 30 步先 compose 到 base 系，再切片**，不能切片后各自用不同锚点。
2. **夹爪**：WLA 归一化 → 挑战赛范围；用实测 0–4.5，方向先探测；clip。
3. **pivot**：
   ```text
   pivot = [0, 0, 0, 0, p4_task, 0, height_task]
   ```
   - `p4_task`/`height_task` 来自 TASK-MEM；默认 0.150/0.738。
   - `vx/vy/angle_z` 站立桌面任务先置 0；单任务通道证明有收益再放开。
   - 常量任务用常量；变化任务用相位 profile。
4. **hand/legs/waist/torso**：挑战赛 `ee` 不直接下发；作为辅助损失或屏蔽；不要偷偷映射到 pivot。
5. **state 60D**：按 WLA 训练分布填；缺失的手/腿用默认/上一帧；归一化用 q01/q99，不用极端 min/max。
6. **chunk**：WLA 30 步 @30Hz；若挑战赛控制频率不同，重采样；切片后保持 base 系绝对目标一致。

### 7.3 延迟/并发

- VLA 异步：`get_action` 用最近完成的 plan + 当前观测伺服；plan 过期阈值 `T_stale`（如 400ms）。
- 过期：WHEEL 可继续短时前馈；PRE_CONTACT/LEG 降增益/重规划；RECOVER 停。
- 多端口共享 GPU：batch/排队；每端口只保留一个 in-flight 请求；p99 延迟要测。
- CPU 检索：top-k 分桶 + 预计算特征；目标 <10ms。

## 8. 实验与竞赛策略

### 8.1 G0–G8

| 门 | 问题 | 最小实验 | 过门标准 | 失败则 |
|---|---|---|---|---|
| G0 | 数据/标定可用 | 32 任务 lag/内参/夹爪/pivot 审计；HangCup/ZipUp 全 shard 复核 | lag 稳定；fx 可解释；夹爪方向一致 | 先修数据，不训 |
| G1 | 记忆可检索 | 离线 top-k：目标位姿误差、相位准确率、恢复命中 | top-5 目标误差 ≤1cm/5°；相位 ≥80% | 降库/改特征 |
| G2 | lag 对齐涨点 | 对齐 vs 不对齐，同数据微调 | 单任务 +≥5pp 或误差显著降 | 回退 |
| G3 | 质量加权涨点 | 均匀 vs DQ 加权；保留 vs 删恢复段 | DQ ≥ 均匀；恢复段不伤害 | 调权重/回退 |
| G4 | stance 记忆涨点 | pivot 全零 vs 任务常量 vs 相位 profile | 不降；接触任务 +≥3pp | 只留常量 |
| G5 | 双频优于固定 | H=30/10/5/3 + router | 接触 +≥5pp；自由空间不慢 | 改阈值/回退 5 |
| G6 | 域差鲁棒 | AV1 vs JPEG q95、颜色/压缩扰动 | 掉点 ≤3pp | 加增强/校准 |
| G7 | 单任务真机 | A 档 5 任务，30–50 trials | 配对增益显著、无安全异常 | 缩小范围 |
| G8 | 全量 320 trials | 32×10 | 成功率/步骤分优于基线，无端口/超时故障 | 回滚 |

### 8.2 指标

- 主：成功率、步骤分（官方）。
- 辅：time-to-first-contact、contact success rate、recovery success rate、chunk rejection rate、p95 latency、safety violations、gripper scale error、pivot 实际值。
- 统计：配对 bootstrap 95% CI；单任务 10 次噪声大，测试通道尽量 30–50 次；不要用非配对均值比较。

### 8.3 任务组合

```text
priority_t = q_task_t * Δ_contact_t * Δ_memory_t / cost_t
```

- `q_task`：数据质量（lag/标定/夹爪/长度/覆盖）。
- `Δ_contact`：接触段失败占比（先验，单任务通道更新）。
- `Δ_memory`：记忆预期增益（腕部视野稳定、stance 任务化、有恢复段）。
- `cost`：工程/评测成本。

先验分档（**不是榜单排名**）：

| 档 | 任务 | 理由 |
|---|---|---|
| A（先做） | T01 HangCup、T05 DisconnectEthernet、T10 PlugCharger、T12 Unlock、T13 ArrangeTestTubes、T19 ZipUp、T26 PlugInEthernet、T27 StackBowls、T09 ToolboxStorage、T14 PourOutMedicine | 接触明确；腕部视野稳定；成功判据清晰；A 档覆盖挂/拔/插/锁/叠/收纳 |
| B（第二批） | T03 PackDoll、T17 OrganizeStationery、T18 PackBag、T29 PackPhone、T31 OrganizePencilCase、T23 StorePaddle、T28 StoreEarphones | 双臂/长程/目标多，记忆增益中等 |
| C（观察） | T16 FoldTowel、T24 ConveyorSorting、T22 SpellRobot、T04 FruitSorting、T06 ColorArrangement | 变形/动态/语义主导，接触记忆增益低 |

风险标记：

- T08/T19/T27 头部 fx=186：先修标定。
- T11 height min=0.608：stance profile 必做。
- T15 pivot_4=0.214、T23 pivot_4=0.113：单独 TASK-MEM。
- T05 左臂 lag=7、T25 左臂 lag=0：per-arm lag，不要全局 3。
- T09 37.6s、T23 34.1s：长任务，步骤/超时风险高。

### 8.4 提交节奏

1. **安全基线**：WLA + adapter + 合法 pivot；锁端口/token/超时；若允许多次提交，先交基线锁 tie-break。
2. **数据修正版**：lag 对齐 + per-task 标定 + 夹爪尺度 + codec 增强；H=30。
3. **DQ 微调版**：action-head 质量加权；H=30。
4. **记忆版**：TASK-MEM + CONTACT-MEM；H=5–10；pivot/height 检索。
5. **router 版**：WHEEL-LEG；保留回滚开关。
6. **全量 320 trials**：只在单任务通道过门后跑；不要用正式提交做探索。

### 8.5 72 小时执行清单

- **0–8h**：G0 审计；复算 lag；读 32 任务 camera_params；写夹爪/ pivot 探测脚本。
- **8–24h**：HangCup/ZipUp/StackBowls 三个任务建 DQ-SCORE + 记忆原型；跑离线 top-k 评估。
- **24–48h**：单任务通道跑基线 vs 数据修正 vs 记忆；记录失败相位/实测 pivot/夹爪范围。
- **48–72h**：决定是否开 router；若记忆无增益，回退到 G2/G3 的数据修正版；不要继续堆模块。

## 9. 风险与合规

### 9.1 未核实/高风险

| 项 | 风险 | 处理 |
|---|---|---|
| 线上控制频率 | 假设 30Hz，若不同则 chunk 时间错 | 单任务通道测时间戳；重采样 |
| RTT 分布 | 远程 API 抖动，chunk 过期 | 异步 + plan 过期降增益 |
| 夹爪范围/方向 | 0–4.5 vs 5.5→0，方向未知 | 小步探测；clip；保守开度 |
| pivot 语义 | 只写“Lower-body / pivot target” | 小步 A/B；不猜符号/单位 |
| 是否允许多次提交 | 影响 tie-break/探索 | 先问官方；默认保守 |
| WLA 是否覆盖 32 任务 | 可能未见过某些任务 | 先跑 baseline；失败任务用记忆/规则 |
| 人为干扰协议 | 具体方式未知 | RECOVERY-MEM + edit_score + 保守重试 |
| 真实失败分布 | 榜单是预览 | 单任务通道统计，不用榜单反推 |

### 9.2 合规

- 一个 WLA checkpoint；DQ-MEM 是数据/索引，不是第二个策略。
- 检索默认非学习特征（ORB/颜色/轮廓/几何）；用 WLA 自身 encoder 优先；第三方编码器先问官方。
- 评测中不更新权重/索引；只读。
- 记忆构建脚本/质量分/索引版本随提交包记录。
- 任何异常回退上一组合法 chunk 或安全 hold；不返回 NaN/错误形状。

### 9.3 安全

- 动作 clamp：位置/旋转/夹爪/时间。
- workspace bounds；max delta；timeout。
- 接触段无力反馈：保守增益、短 chunk、视觉残差监控。
- 多端口状态隔离；token 不共享；异常端口隔离。
