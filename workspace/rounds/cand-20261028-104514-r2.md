# 第 11 轮 · TACT-VLA：把延迟折成冲量预算，把接触写成时间尺度，把可用性写成 AURA-32

> 检索/复核日期：2026-10-28（UTC）。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 人形 + 夹爪，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。状态文件上一轮是第 10 轮 FACT-VLA；本轮是新一轮的第 2 次迭代，三个灵感词是「推理延迟」「力控」「可用性评估」。本轮不推倒 FACT-VLA，而是把它降为接触相位与恢复骨架，把主火力移到**时间尺度**。

## 0. 先给结论：延迟不是速度问题，是接触时间尺度问题

本轮最重要的判断是：**在 UniBot 的同步分块 API 下，推理延迟 τ 和 chunk 长度 T_a 不是两个独立的工程参数，它们共同决定“下一次看到世界”的周期 C；而 C 又直接乘进接触冲量、决定力控是前馈还是闭环。**

具体拆成四层，共用一个 checkpoint：

1. **LMC（Latency-Matched Chunking）**：把官方语义写成 `C = τ + T_a·Δt`；用占空比 `d = 1 − τ/C` 和反馈频率 `f = 1/C` 描述“延迟—平滑—反应性”三角；在 `C ≈ 2τ–3τ` 的膝点选全局 `T_a`，再用“安全前缀 L + guard tail”把承诺长度和供给长度解耦。
2. **CTAC（Contact Time-scale Adaptive Control）**：把“力控”改写成接触时间尺度控制。瞬态 `T_t` 远小于 C 时，用前馈柔顺 chunk + **IBCC 冲量预算**；保持相 `T_h` 远大于 C 时，用 **CBP 接触信念与探测**；两者之间用混合模式。
3. **DCCT（Delay-Conditioned Contact Training）**：训练时模拟延迟、加 latency token、做 prefix-tail 监督、接触相位加权、冲量感知损失、session-grouped 验证；让一个模型在 d=0 到 d_max 上都稳定，而不是在部署时才发现延迟。
4. **AURA-32**：把“可用性评估”写成四维曲线——Availability（p99/抖动/deadline miss/N 端口隔离）、Usability（`U(τ)=P(success ∧ T≤τ ∧ no safety event)`）、Recovery（`R(τ)`）、Assurance（冲量代理越界/不可逆失败/动作离群）。官方只看成功率与步骤分，AURA-32 看“在什么延迟预算下、可不可用、坏了能不能回来”。

一句话：**先测出每个任务的接触时间常数 `T_c` 和部署环路的 p99 周期 `C=τ+T_aΔt`；`T_c≪C` 的任务用前馈柔顺 chunk，`T_c≫C` 的任务用探测/信念闭环；把延迟折成冲量预算、把可用性写成 AURA-32。**

## 1. 这轮怎么想：三个灵感词是一条链

### 1.1 推理延迟：先问“评测端什么时候再调用我”

官方 README 写得很清楚：`get_action` 返回一个形状为 `(T_a, …)` 的 chunk，index 0 先执行，然后按顺序执行其余动作，**直到评测端再次调用 `get_action`**；`action_chunk_size` 是固定的 `int ≥ 1`。这不是 RTC 论文里“边执行边推理、新 chunk 覆盖旧 chunk”的异步流水线，而是**同步分块**：

```
观测 o_t ──τ──> 返回 a_{t..t+T_a-1} ──T_a·Δt──> 执行完 ──> 下一次观测 o_{t+T_a}
```

因此下一次用于决策的观测，距离上一次观测的时间是：

```
C = τ + T_a·Δt
```

其中 Δt 是控制周期（数据 30 fps 对应 33.3 ms，部署以实测为准）。如果官方实现是流水线（在 chunk 执行期间就发起下一次调用），则 `C = max(τ, T_a·Δt)`；但按 README 的字面语义，先按同步式设计，并用 E1 的时间戳实验确认。

这个式子带来两个直接后果：

- **占空比**：机器人真正在执行动作的时间占比是 `d = T_a·Δt / C = 1 − τ/C`。τ 越大，chunk 之间的停顿越长，动作越“走走停停”。
- **反馈频率**：`f = 1/C`。T_a 越大，动作越平滑、供给越足，但看到新世界越慢；T_a 越小，反应越快，但停顿越多、抖动越大。

所以“推理延迟”不是单纯的“模型快不快”，而是**控制回路的采样周期**。这正好解释了 Microsoft 的测量：π0.5 的 action chunk 生成延迟约 **60 ms（A100）/ 144 ms（Thor）/ 440 ms（Orin AGX）**，在交接任务上成功率是 **80% / 80% / 30%**；报告明确说，高延迟导致 action queue 在生成新 chunk 之前耗尽，出现 stop-and-go 和动作抖动，进而掉精度。延迟不是只影响“快慢”，它改变控制质量。

### 1.2 力控：先问“没有力传感器，力控还剩下什么”

官方观测只有 4 路 RGB、左右臂关节 `[7]`、左右 EE 位姿 `[6]`、左右夹爪 `[1]`、下身体 `[15]`、语言；没有 torque、current、tactile、wrench，也没有力命令通道。ForceVLA2（CVPR 2026）和 FP2 这类工作确实把力做进了 VLA，但它们都依赖**力/力矩信号**；我们的数据与推理 API 都没有这个模态。硬做“力估计”会把目标超前、重力、摩擦、控制器带宽混在一起，第 10 轮已经实测过：原始 `action − next_state` 主要反映目标 lookahead，不是外力。

所以本轮把“力控”改写成三件可观测的事：

1. **接触时间尺度**：接触瞬态 `T_t`（夹爪闭合、插入、拧钥匙的建立时间）和接触保持 `T_h`（抓住之后搬运/等待/操作的时间）。它们决定“一个 chunk 里有多少时间是在开环接触”。
2. **冲量暴露**：不估计牛顿值，只估计“速度 × 开环时间”的量纲。接触时的位移暴露约 `v·(L·Δt + τ)`；若把接触刚度记作 `k̂`，冲量代理 `J ∝ k̂·v·(L·Δt + τ)`。这不是力测量，而是**控制预算**：延迟和承诺长度都会乘进去。
3. **接触信念**：free / soft / hard / jam / slip 五类状态的后验；用夹爪滞止、EE 跟踪残差、腕部视觉接触/光流、物体随动来更新。它不需要力传感器，只需要“接触有没有建立、有没有抵抗、有没有滑”。

数据 pilot 直接支持“两种时间尺度”的判断（首个 parquet、启发式事件、非全量）：HangCup 右夹爪闭合瞬态中位 **0.27 s**、保持中位 **3.13 s**；FoldTowel 瞬态中位 **0.37 s**、保持中位 **4.50 s**；PlugCharger 左/右瞬态中位 **0.07 / 0.27 s**、保持中位 **8.17 / 6.20 s**，保持相占 episode 的 **64.5% / 43.1%**。也就是说：**抓取瞬态常常和 C 同量级，而插入/搬运的保持相远长于 C**。一个全局固定 chunk 不可能同时适合两者。

本报告用 `T_c` 作为接触时间常数的统称：瞬态安全看 `T_t`，保持闭环看 `T_h`；需要单一数时按控制目标取 `T_c=min(T_t,T_h)`（偏安全）或 `T_c=T_h`（偏保持）。

### 1.3 可用性评估：先问“除了成功率，官方还在记录什么”

官方 README §6 明确：评测过程会记录每次 `get_action` 的延迟、延迟波动、返回动作的统计规律性，并可能把这些指标和结果一起展示；建议保持每步延迟平滑稳定、动作良构、避免异常离群。换句话说，**官方已经在做“可用性评估”的原始采集，只是没有把它写成选手可优化的指标**。

本轮把它写成 AURA-32：

- **Availability**：p50/p99 延迟、抖动、deadline miss、N 端口隔离、队列等待、watchdog 回退率。
- **Usability**：`U(τ)=P(success ∧ T≤τ ∧ no safety event)`；`S(τ)=E[step_score·1(T≤τ)]`；time-to-success；在 τ ∈ {5,10,20,30,60,180}s 上的 AURA 曲线。
- **Recovery**：`R(τ)=P(偏离后 τ 秒内恢复)`；用 RoboRecover 式的 deviation 注入测重抓、回撤、重对齐。
- **Assurance**：每 100 次试验的冲量代理越界、不可逆失败（掉落/碰撞/卡死）、动作离群、token/shape 违规。

统计功效必须先说清楚：总 n=320 时，p≈0.3 的 SE≈**2.56 pp**；每轴 n=64 时 SE≈**5.73 pp**；每任务 n=10 时 SE≈**14.49 pp**；每任务每轴 n=2 时 SE≈**32.4 pp**。所以 AURA-32 不能拿单任务小差异讲故事，只能看任务族、轴聚合和大效应。

## 2. 六个硬事实

### 2.1 API 是同步位置接口，不是力接口，也不是异步 RTC 接口

官方 Submission Template（`unitreerobotics/unibot_submission`，commit `edd0a1c9`，2026-08-21）明确：

- 策略实现 `metadata`、`get_action(obs)`、`reset()`；`control_space` 只能是 `"joint"` 或 `"ee"`，二者互斥。
- `action_chunk_size` 是固定 `T_a`；每次返回 `(T_a, …)`；index 0 先执行，直到评测端再次调用。
- `obs_delta_indices` 决定发送哪些观测、每帧偏移；可以请求历史帧，但增加带宽/延迟。
- `meta.token` 必须出现在**每一次** `get_action` 返回值里。
- 观测含 4 路 RGB、左右臂关节、左右 EE 位姿、左右夹爪、下身体、语言；**没有 torque/current/tactile/force**。
- 多台测试机器人要求暴露 N 个连续端口 `8765..8765+N−1`；共享模型必须处理并发与每端口状态隔离。
- §6 记录延迟、波动、动作规律性。

### 2.2 评分是 32×10，5 轴×2，180 s，成功率优先、步骤分决胜

官方规则（Feishu 中文/英文，2026-10-28 可读）：32 个任务，每任务 10 次；5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰）各 2 次；单次 180 s；超时记失败但仍按执行情况计算步骤分；排名先总平均成功率，再总平均步骤分，再更早提交；只允许单模型；有不计分的单任务测试通道。

### 2.3 榜单是种子数据，不是可复现 SOTA

首页榜单（2026-10-28）：MolmoAct/DexHacker **29.7% / 39.0**，WALLOSS 28.5% / 38.9，DreamZero 27.9% / 37.9，第 8 名 gr00t 20.5% / 28.1。独立排行榜页仍显示 “Coming Soon”，榜单 JSON 的 `generated_from` 是 `gen_leaderboard.py`，details/runs 是占位。结论：**不要把公开排行当任务难度表，也不要把 29.7% 当不可追赶的真机 SOTA**；头部与第 8 名只差 9.2 pp，方法和数据管线仍有空间。

### 2.4 数据是 33,276 条成功演示，169.28 h，30 fps，4 相机，无接触标签

32 个 HF LeRobot v3 数据集：33,276 episodes、18,282,246 frames、169.28 h、30 fps、4 相机、192 sessions、77 个采集日期（2026-02-05 至 06-25）；每任务 5 条语言指令；任务级 robot 组合合计 94，最大单任务 6 个 robot。**没有 force/torque/tactile 标签**；所有接触监督必须从夹爪、EE、视觉和动作里弱监督。

### 2.5 任务卡把“接触”写得很具体

官方任务卡（`tasks_v2/<slug>/info.json?v=2026-07`）公开 100 分 rubric。抽样：HangCup 2×50（抓杯把 / 挂到标记位）；PlugCharger 3 步 30/30/40（抓插排 / 抓插头 / 插入）；Unlock 3 步 30/30/40（抓起锁 / 拧钥匙 / 拨铁环）；FoldTowel 5×20（挥正 / 上下折 / 左折 / 右折 / 放旁边）；ZipUp 2×50（摆正 / 拉拉链）；SyringeWaterTransfer 2×50（吸液 / 注液）。这些任务的共同点不是“力大”，而是**接触建立快、保持/操作时间长、失败多发生在接触段**。

### 2.6 外部证据：延迟、chunk、调度、恢复都已经被单独研究，但没有人把它们合成“接触时间尺度”

- VLA-HWBench（2610.34717）：18 个 VLA 在 Jetson Thor / AMD 上做七阶段拆解；action-generation 策略比模型大小更重要，Jetson 上延迟差 **82×**、AMD 上 **157×**，参数量最多解释 **15%** 的延迟方差。
- TT-RTC（2512.05964）：训练时模拟延迟 + 直接条件在 action prefix 上，高延迟下优于 inference-time RTC，且无推理开销。
- 异步推理系统比较（2605.08168）：A2C2 的 per-step residual correction 在 Kinetix 上 d=8 仍 >90%；不同方法必须统一协议比较。
- VLASH（2512.01031）：异步推理的 temporal misalignment 会导致动作不稳定。
- PICES（2610.19656）：一次策略调用内联合选 chunk 和执行 horizon；CA3C（2610.07949）：用 imagined futures 的一致性决定 commit 长度；AAC（2604.04161）：用动作熵自适应 chunk size。
- Armory（2608.00337）：多机器人共享 GPU 时，naive batching 在“不同机器人以不同速率消费 chunk”时失效；考虑异构的调度可提升吞吐 **18%**。
- vla.simd（2609.24274）：明确区分 **action supply** 与 **feedback frequency**；延迟与执行 horizon 共同决定 action availability。
- FP2（2609.37433）/ ForceVLA2（2603.15169）：显式力控需要 wrench/force 信号；我们的 API 没有。
- RoboRecover（2609.28952）：初始状态性能不能决定恢复性能；恢复需要单独的 deviation 基准。
- 可用性研究（2602.03920）：非专家会用 TSR，但也需要失败描述和风险信息才能理解 RFM 能力。

## 4. TACT-VLA 四层

### 4.1 LMC：延迟匹配分块

**定义**：Δt 控制周期，T_a 固定 chunk 长度，τ 推理延迟，C 有效反馈周期。

**同步分块（README 字面语义）**：

```
C = τ + T_a·Δt
d = T_a·Δt / C = 1 − τ/C
f = 1/C
```

**流水线（若官方提前调用）**：

```
C = max(τ, T_a·Δt)
d = min(1, T_a·Δt/τ)
```

**膝点**：给定目标占空比 d_min，`C* = τ/(1−d_min)`，`T_a* = ceil(τ·d_min / ((1−d_min)·Δt))`。例如 τ=100 ms、Δt=33.3 ms：

| T_a | C | 占空比 d | 反馈 f |
|---:|---:|---:|---:|
| 1 | 133 ms | 25.0% | 7.5 Hz |
| 2 | 167 ms | 40.0% | 6.0 Hz |
| 3 | 200 ms | 50.0% | 5.0 Hz |
| 6 | 300 ms | 66.7% | 3.3 Hz |
| 12 | 500 ms | 80.0% | 2.0 Hz |
| 30 | 1100 ms | 90.9% | 0.9 Hz |

**供给—承诺解耦**：`T_a` 决定 C（反馈周期），`L ≤ T_a` 决定真正“任务相关”的承诺前缀；尾部填保持/回撤/减速。这样可以在不改变 C 的情况下，按接触相位缩短承诺长度。**不要把“chunk 长度”和“承诺长度”混为一谈**。

**全局 T_a**：`action_chunk_size` 是整个 submission 固定的，不能按任务改；所以 T_a 要按任务混合和 τ_p99 在膝点选一次。E1 扫 `T_a ∈ {1,2,3,4,6,8,12,16,24,32,50}`，测 C、占空比、成功率、步骤分、动作抖动，选 Pareto 点。

### 4.2 CTAC：接触时间尺度自适应控制

**两个时间尺度**：

- `T_t`：接触瞬态（夹爪闭合、插入、拧钥匙的建立时间）。
- `T_h`：接触保持（抓住之后搬运/等待/操作的时间）。
- `ρ_t = T_t/C`，`ρ_h = T_h/C`。

| 区域 | 判据 | 控制策略 | 典型任务 |
|---|---|---|---|
| 快瞬态、短保持 | `ρ_t < 1`，`ρ_h < 1` | 前馈柔顺 chunk：慢接近、限速闭合、尾部保持/回撤 | HangCup 抓取、ZipUp 起拉 |
| 快瞬态、长保持 | `ρ_t < 1`，`ρ_h ≥ 3` | 前馈插入 + 保持相 CBP 探测/信念 | PlugCharger、Unlock、Syringe |
| 快瞬态、中保持 | `ρ_t < 1`，`1 ≤ ρ_h < 3` | 前馈 + 单次 probe / 边界 replan | ZipUp 中段、Unlock 对键 |
| 慢接触 | `ρ_t ≥ 1` | 从接触开始就闭环：更短 L、更多 replan、probe | FoldTowel、可变形物体 |

**IBCC（Impulse-Budgeted Contact Control）**：

```
J_norm = v · (L·Δt + τ_p99) / s_obj
v_max(task, phase) = B_task / (k̂ · (L·Δt + τ_p99))
```

`J_norm` 是归一化位移暴露，不是力；`k̂` 是从自由空间/已知物体校准的相对刚度代理；`B_task` 是任务级预算。控制规则：

- 接触相速度上限 `v_max`；接近相减速到 `v_contact`；插入相用 `v_contact` 和短 L。
- 加速度/加加速度上限，避免 chunk 边界跳变。
- 接触相 `L` 上限（例如 3–6 步），尾部填保持/回撤；自由相可以用满 T_a。
- 如果 `J_norm` 超过预算，先降速，再缩短 L，最后回退到 hold/retreat；不靠“更用力”解决。

一个数量级例子：v=10 cm/s、L=6、Δt=33 ms、τ=100 ms，开环位移 `v·(L·Δt+τ)=3 cm`；插入公差常常只有毫米级。即使 v=2 cm/s，也是 6 mm。**这就是为什么接触相必须限速 + 柔顺 + 短承诺，而不是把位置 chunk 开环执行完。**

**CBP（Contact Belief & Probing）**：

- 信念 `b ∈ Δ{free, soft, hard, jam, slip}`；观测：夹爪指令 vs 实际开合的滞止、EE 指令 vs 实际位姿的跟踪残差（去延迟后）、腕部视觉接触/光流、物体是否随夹爪运动。
- Probe 原语：press（小幅下压）、wiggle（小幅横向）、rotate（小幅旋转）、retreat（回撤）、re-grasp（重抓）、re-align（重对齐）。
- 选择准则：`probe* = argmax [IG(probe) − λ·risk(probe) − μ·time(probe)]`；只在 `ρ_h ≥ 3` 且信念熵高于阈值时启用；信念收敛或风险超预算就停止。
- 这不是世界模型，也不是 RL；是一个轻量、可解释、可回退的接触状态机。

### 4.3 DCCT：延迟条件化的接触训练

训练样本：在演示时间 t，采样延迟 `d ~ U{0..d_max}`（混合一部分 d=0 保 nominal），输入 `obs_{t−d}` 和已执行前缀 `a_{t−d..t−1}`，目标 `a_{t..t+T_a−1}`。这对应 TT-RTC 的思想，但加了三件接触相关的事：

1. **Latency token**：把 `d/d_max` 编码进模型（embedding 或 FiLM），让一个 checkpoint 覆盖多个延迟，而不是训练多个模型。
2. **Prefix-tail 监督**：自由相全 chunk 监督；接触相只对前 L 个动作算主损失，尾部用保持/回撤/减速作为辅助目标；避免教模型“接触时继续猛推”。
3. **Impulse-aware loss**：`L_imp = max(0, J_norm − B_task)^2`，只作用在接触相；同时惩罚接触相的加速度/加加速度。
4. **Contact-phase weighting**：接触帧加权 3–5×，但设上限，避免自由空间回归；相位标签用夹爪事件 + 视觉 + 少量人工审计（约 160 段）。
5. **Session-grouped validation**：按 session/robot/date 切分，不按帧随机切；否则同一段轨迹泄漏，延迟鲁棒性会被高估。

总损失：

```
L = L_action + λ_phase·L_phase + λ_progress·L_progress + λ_imp·L_imp
```

`L_phase` 是 6 类接触相位（free / approach / contact / grasp / transport / release）的辅助 CE；`L_progress` 是轻量步骤进度头，只用于恢复，不用于刷步骤分。

### 4.4 AURA-32：可用性评估

**Availability**：

- 每步 p50/p99 延迟、抖动（p99−p50）、deadline miss（`C > C_budget`）、队列等待、watchdog 回退率。
- N 端口隔离：每个端口独立 episode 状态；并发压测下无串扰、无相互阻塞。

**Usability**：

```
U(τ) = P(success ∧ T ≤ τ ∧ no safety event)
S(τ) = E[step_score·1(T ≤ τ)]
AURA-AUC = (1/τ_max) ∫ U(τ) dτ
```

τ 网格：5/10/20/30/60/180 s。`U(τ)` 比单一成功率更接近“部署可用性”：一个 170 s 才成功、且中途撞了两次的策略，和 15 s 干净成功的策略，成功率一样，但可用性不一样。

**Recovery**：

```
R(τ) = P(偏离后 τ 秒内恢复)
```

偏离注入：物体被移动、抓取滑落、插入卡住、拉链回退；用 RoboRecover 式 replay/重建；恢复原语：re-grasp、retreat、re-align、re-probe。

**Assurance**：

- 每 100 次试验的 `J_norm` 越界次数。
- 不可逆失败率（掉落、碰撞、卡死、需要人工复位）。
- 动作离群率（chunk 边界跳变、速度/加速度越界）。
- token/shape/端口协议违规次数（应为 0）。

**统计功效**：n=320/64/10/2 的 SE 见 §1.3；AURA 报告必须给置信区间，不能拿单任务 1–2 次差异当结论。

### 4.5 N 端口服务

- **Approach 1（最稳）**：每端口一个进程、各自加载模型；隔离最好，显存 N 倍。
- **Approach 2（省资源）**：N 个轻量 endpoint + 一个共享推理后端；continuous batching、per-port 状态、EDF/ deadline 调度；注意不同机器人消费 chunk 的速率不同（Armory 的教训）。
- **Watchdog**：队列等待超过预算时，返回安全的 hold/retreat chunk，而不是让机器人等；记录回退率。
- **工程**：warmup、CUDA graphs、FP8/INT8、图像 resize、pinned memory、零拷贝、token 校验、延迟遥测。
- **压测**：N ∈ {1,2,3,4,6,8} 并发，测每端口 p99、抖动、deadline miss、状态隔离；不能只看总吞吐。

# 第 11 轮产物区 · TACT-VLA 技术报告（Time-scale Adaptive Contact-safe VLA for UniBot）

> 目标赛事：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 人形 + 夹爪，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。检索/复核日期：**2026-10-28（UTC）**。本报告承接第 10 轮 FACT-VLA（Force-proxy Aware Contact-phase Training），但主火力从“接触相位”推进到“接触时间尺度”：不假设有力传感器，不把同步分块 API 当成异步 RTC，而是把延迟、chunk 长度、接触瞬态/保持、可用性写进同一个控制回路。

## 0. 产物摘要

**目标**：在 32 任务 × 10 次、5 泛化轴 × 2 次、单次 180 s、单模型的约束下，给出一个能在官方同步分块 API 上落地的方案，撬动“延迟—接触—可用性”这条被公开材料忽略的杠杆，而不是再堆一个更大的 VLA。

**方法**：TACT-VLA 四层，共用一个 checkpoint：

1. **LMC（Latency-Matched Chunking）**：把官方语义写成 `C = τ + T_a·Δt`；用占空比 `d = 1 − τ/C` 和反馈频率 `f = 1/C` 描述延迟—平滑—反应性三角；在 `C ≈ 2τ–3τ` 的膝点选全局 `T_a`，再用“安全前缀 L + guard tail”解耦承诺长度与供给长度。
2. **CTAC（Contact Time-scale Adaptive Control）**：按 `ρ_t=T_t/C`、`ρ_h=T_h/C` 分三区；快瞬态用前馈柔顺 chunk + **IBCC 冲量预算**；长保持用 **CBP 接触信念与探测**；慢接触从开始就闭环。
3. **DCCT（Delay-Conditioned Contact Training）**：延迟增广、latency token、prefix-tail 监督、接触相位加权、冲量感知损失、session-grouped 验证；一个模型覆盖 d=0..d_max。
4. **AURA-32**：Availability（p99/抖动/deadline miss/N 端口隔离）、Usability（`U(τ)`、`S(τ)`、AURA-AUC）、Recovery（`R(τ)`）、Assurance（冲量代理越界/不可逆失败/动作离群）。

**关键数字**：

- 赛事：32 任务 ×10 次 = 320 次；5 轴 ×2；180 s；成功率 → 步骤分 → 更早提交；单模型；N 个连续端口；§6 记录延迟/抖动/动作规律性。
- API：`action_chunk_size` 固定 `T_a`；`get_action` 返回 `(T_a,…)`，index 0 先执行，直到评测端再次调用；无 torque/current/tactile/force；`meta.token` 每次都要带。
- 数据：33,276 eps / 18,282,246 frames / 169.28 h / 30 fps / 4 相机 / 192 sessions / 77 个日期 / 每任务 5 条指令；无接触标签；0 条 >180 s。
- Pilot：夹爪闭合瞬态中位 **0.07–0.37 s**；保持中位 **3.13–8.17 s**；PlugCharger 保持相占 episode 的 **64.5% / 43.1%**（左/右）。两种时间尺度差一个数量级以上。
- 延迟：π0.5 action chunk 生成约 **60 ms（A100）/ 144 ms（Thor）/ 440 ms（Orin AGX）**；交接任务成功率 **80% / 80% / 30%**；高延迟导致 action queue 耗尽、stop-and-go、抖动。
- 榜单：MolmoAct/DexHacker **29.7% / 39.0**，WALLOSS 28.5% / 38.9，DreamZero 27.9% / 37.9，第 8 名 20.5% / 28.1；JSON `generated_from=gen_leaderboard.py`，details/runs 占位。
- 统计功效：n=320 时 SE≈2.56 pp；每轴 n=64 时 5.73 pp；每任务 n=10 时 14.49 pp；每任务每轴 n=2 时 32.4 pp。

**六个交付物**：① LMC 公式与 `T_a` 选择表；② CTAC/IBCC/CBP 的运行时状态机；③ DCCT 的训练/验证协议；④ AURA-32 的指标与压测协议；⑤ N 端口服务架构；⑥ E1–E7 实验、G0–G7 门控、资源阶梯。

**一句话**：把延迟折成冲量预算、把接触写成时间尺度、把可用性写成 AURA-32；先测 `T_c` 与 `C`，再决定前馈还是闭环。

这些任务卡说明：**接触不是“一个动作”，而是“瞬态 + 保持 + 操作”的组合**。一个全局 chunk 长度无法同时适配 0.1 s 的闭合瞬态和 8 s 的插排保持。

## 2. 问题形式化

### 2.1 同步分块时序

设：

- `Δt`：控制周期（数据 30 fps → 33.3 ms；部署实测）。
- `T_a`：固定 chunk 长度。
- `τ`：一次 `get_action` 的端到端延迟（含网络、预处理、模型、后处理）。
- `C`：两次“用于决策的观测”之间的有效周期。

同步分块（README 字面语义）：

```
观测 o_t
  │
  ├── τ ──────────────► 返回 a_{t..t+T_a−1}
  │                         │
  │                         ├── T_a·Δt ──► 执行完
  │                         │
  │                         └── 下一次观测 o_{t+T_a}
  │
  C = τ + T_a·Δt
```

流水线（若 evaluator 提前调用）：

```
C = max(τ, T_a·Δt)
```

占空比与反馈频率：

```
d = T_a·Δt / C = 1 − τ/C          （同步）
d = min(1, T_a·Δt/τ)              （流水线）
f = 1/C
```

**解释**：

- `τ` 固定时，`T_a` 越大，`C` 越大，`d` 越高、`f` 越低。
- `T_a` 越小，`f` 越高，但 `d` 越低、停顿越多、动作越容易抖。
- 这就是“延迟—平滑—反应性”三角；不存在一个对所有任务都最优的 `T_a`。

### 2.2 膝点与 `T_a` 选择

给定目标占空比 `d_min`：

```
C* = τ/(1 − d_min)
T_a* = ceil(τ·d_min / ((1 − d_min)·Δt))
```

例：`Δt=33.3 ms`。

| τ | d_min=50% | d_min=66.7% | d_min=80% |
|---:|---|---|---|
| 60 ms | T_a=2, C=127 ms | T_a=4, C=193 ms | T_a=8, C=327 ms |
| 100 ms | T_a=3, C=200 ms | T_a=6, C=300 ms | T_a=12, C=500 ms |
| 440 ms | T_a=14, C=907 ms | T_a=27, C=1340 ms | T_a=53, C=2207 ms |

这张表说明：**部署硬件/推理优化直接改变最优 chunk 长度**。如果我们在 A100 上把 τ 压到 60 ms，`T_a=4` 就能到 67% 占空比、193 ms 反馈周期；如果掉到 Orin 的 440 ms，同样的占空比需要 `T_a=27`，反馈周期 1.34 s，接触任务基本没法做。所以“模型量化/编译/图像 resize”不是单纯加速，它把 `T_a` 和 `C` 一起改写。

### 2.3 接触时间尺度

定义：

- `T_t`：接触瞬态时间（从夹爪/EE 开始接触，到建立稳定接触/闭合/插入的近似时间）。
- `T_h`：接触保持时间（接触建立后，持续抓握/插入/操作的时间）。
- `ρ_t = T_t/C`，`ρ_h = T_h/C`。本报告用 `T_c` 作为统称：瞬态安全看 `T_t`，保持闭环看 `T_h`；需要单一数时按控制目标取 `T_c=min(T_t,T_h)`（偏安全）或 `T_c=T_h`（偏保持）。

三区：

| 区域 | 判据 | 控制 |
|---|---|---|
| 快瞬态、短保持 | `ρ_t < 1`，`ρ_h < 1` | 前馈柔顺 chunk；慢接近、限速闭合、尾部保持/回撤 |
| 快瞬态、长保持 | `ρ_t < 1`，`ρ_h ≥ 3` | 前馈插入 + CBP 探测/信念 |
| 快瞬态、中保持 | `ρ_t < 1`，`1 ≤ ρ_h < 3` | 前馈 + 单次 probe / 边界 replan |
| 慢接触 | `ρ_t ≥ 1` | 从接触开始就闭环；短 L、多 replan、probe |

**冲量暴露**：

```
J_norm = v · (L·Δt + τ_p99) / s_obj
```

- `v`：接触相指令速度。
- `L`：承诺前缀长度（≤ T_a）。
- `s_obj`：物体特征尺度（例如 10 cm）。
- `J_norm` 是“开环位移暴露”的归一化，不是力；它只要求单调、可比较、可设预算。
- 力代理记作 `J_force ∝ k̂·J_norm`；控制用 `J_norm`，因为 `k̂` 不可校准，`J_force` 只用于相对排序/安全校准。

例：`v=10 cm/s`、`L=6`、`Δt=33 ms`、`τ=100 ms`：

```
J_norm = 0.1 m/s · (0.2 s + 0.1 s) / 0.1 m = 0.3
开环位移 = 3 cm
```

插入公差常常只有毫米级；3 cm 的开环位移足以把插头顶弯/顶飞。即使 `v=2 cm/s`，也是 6 mm。**所以接触相必须限速 + 柔顺 + 短承诺；延迟和 L 都是冲量的乘数。**

### 2.4 为什么不是显式力控/异步 RTC

- **显式力控**：ForceVLA2/FP2 需要 wrench/force 输入或力命令输出；UniBot 的观测和动作都没有。硬做力估计会把目标超前、重力、摩擦、控制器带宽混在一起；第 10 轮实测 `action−next_state` 主要反映 lookahead。结论：只能做位置域接触代理。
- **异步 RTC**：RTC/TT-RTC/VLASH 假设“边执行边推理、新 chunk 覆盖旧 chunk”；UniBot 的 README 语义是“执行完 chunk 再调用”。把异步 RTC 原样搬来会误判 `C`，也会引入不必要的 inpainting 开销。结论：保留 TT-RTC 的“训练时延迟条件”，但不假设异步执行。

## 3. 方法：TACT-VLA

### 3.1 总览

```
                         ┌─────────────────────────────┐
obs (4 cam + joint + EE) │  shared VLA backbone (LoRA) │
        + language  ────►│  + latency token            │
                         └──────────────┬──────────────┘
                                        │
                 ┌──────────────────────┼──────────────────────┐
                 ▼                      ▼                      ▼
          action chunk head      contact-phase head      progress head
                 │                      │                      │
                 ▼                      ▼                      ▼
          LMC: T_a, L, tail       CTAC: IBCC/CBP         recovery triggers
                 │                      │                      │
                 └──────────────────────┴──────────────────────┘
                                        ▼
                              AURA-32 telemetry / N-port serving
```

### 3.2 LMC：延迟匹配分块

**离线**：

1. 在目标硬件上测 `τ` 的 p50/p99 与抖动；测 `Δt`。
2. 选 `d_min`（建议 2/3；接触任务可 1/2，长保持可 3/4）。
3. 用 §2.2 公式算 `T_a`；在 E1 中扫邻近值，选 Pareto 点。
4. 记录 `C_budget = τ_p99/(1−d_min)`，作为 AURA 的 deadline。

**运行时**：

```
输入: 当前相位 p, 接触信念 b, T_a, L_contact, L_free
if p in {free, approach}:
    L = L_free = T_a
else:
    L = min(T_a, L_contact)
tail = safe_hold_or_retreat(p, b)
return [a_0..a_{L-1}] + tail
```

**注意**：

- `T_a` 是 metadata 固定值，不能按任务改；`L` 可以按相位改，但 evaluator 仍会执行满 `T_a`，所以尾部必须是安全动作。
- `C` 由 `T_a` 决定，不由 `L` 决定；`L` 只改变“承诺多少”，不改变“多久看到下一次”。
- 如果官方是流水线，`T_a` 选 `ceil(τ/Δt)` 即可让 `C≈τ`；E1 会告诉我们到底是哪一种。

### 3.3 CTAC：接触时间尺度自适应控制

#### 3.3.1 相位与时间尺度

6 类相位：free、approach、contact、grasp、transport、release。相位头输出软标签；时间尺度 `T_t/T_h` 来自离线任务统计 + 在线事件检测。

在线事件：

- 夹爪闭合指令开始 → 夹爪开合变化 < 阈值 → `T_t` 开始。
- 夹爪开合稳定在闭合平台 → `T_h` 开始。
- 夹爪重新打开/物体随动消失 → `T_h` 结束。

#### 3.3.2 IBCC

**预算**：

```
B_task = quantile_90(J_norm | 成功演示, task)
v_max = B_task · s_obj / (k̂ · (L·Δt + τ_p99))
```

`k̂` 用相对刚度代理：自由空间响应 / 已知物体响应；不声称牛顿。控制：

| 相位 | 速度 | L | 尾部 |
|---|---|---|---|
| approach | 中速，末段减速 | T_a | 减速/停 |
| contact | `v_contact` | 3–6 | hold/retreat |
| grasp | 慢闭合到滞止 | 3–6 | hold |
| transport | 中速，限加速度 | T_a | hold |
| release | 慢开 | 3–6 | retreat |

**触发**：

- `J_norm > B_task`：先降速 30%，再缩 L 到 3，最后 hold/retreat。
- 跟踪残差 > 阈值（去延迟后）：认为遇到硬接触/卡住，进入 CBP 或 retreat。
- 夹爪滞止但物体未随动：可能滑/未抓稳，re-grasp。

#### 3.3.3 CBP

信念 `b = [p_free, p_soft, p_hard, p_jam, p_slip]`。观测模型（示例）：

| 观测 | free | soft | hard | jam | slip |
|---|---|---|---|---|---|
| 夹爪开合变化 | 大 | 中 | 小 | 极小 | 中 |
| EE 跟踪残差 | 小 | 中 | 大 | 大 | 小 |
| 腕部接触/光流 | 无 | 有 | 有 | 有 | 有 |
| 物体随动 | 无 | 有 | 有 | 无 | 部分 |

Probe 原语：

| 原语 | 动作 | 目的 | 风险 |
|---|---|---|---|
| press | 小幅下压 2–5 mm | 建立接触/判断软硬 | 顶坏 |
| wiggle | 小幅横向 ±2 mm | 找插入角 | 刮擦 |
| rotate | 小幅旋转 ±2° | 对键/螺纹 | 卡死 |
| retreat | 回撤 5–10 mm | 解除卡住 | 掉落 |
| re-grasp | 张开→闭合 | 修正抓取 | 时间 |
| re-align | 视觉重对齐 | 修正位姿 | 时间 |

选择：

```
probe* = argmax_{probe} [ IG(probe) − λ·risk(probe) − μ·time(probe) ]
```

只在 `ρ_h ≥ 3` 且 `H(b) > H_min` 时启用；`H(b) < H_min` 或风险超预算就停止，回到前馈/保持。这样不会在每个任务上都“抖来抖去”，只在长保持相、信念不确定时探测。

#### 3.3.4 运行时状态机

```
free ──接近──► approach ──接触事件──► contact
                                      │
                         ┌────────────┼────────────┐
                         ▼            ▼            ▼
                      grasp       insert/probe   retreat
                         │            │            │
                         └──────► transport ◄──────┘
                                      │
                                      ▼
                                   release
```

状态机输出：相位、`L`、速度上限、是否 probe、是否 recovery。所有输出都可被 watchdog 覆盖为 hold/retreat。

### 3.4 DCCT：延迟条件化的接触训练

#### 3.4.1 样本构造

对每个演示时间 `t`：

```
d ~ U{0..d_max}（混合 20% d=0）
输入: obs_{t−d}, prefix a_{t−d..t−1}, language
目标: a_{t..t+T_a−1}
```

`d_max` 由部署 `τ_p99/Δt` 决定（例如 20 步 ≈ 0.67 s）；训练分布要覆盖比部署更长的尾部，保证 OOD 稳定。

#### 3.4.2 Latency token

把 `d/d_max` 编码为一个小 embedding，加到 backbone 的 conditioning 上（或 FiLM）。一个 checkpoint 覆盖多个延迟；不需要为每个延迟训一个模型，也不需要在推理时做 inpainting。

#### 3.4.3 Prefix-tail 监督

- 自由相：全 chunk 监督。
- 接触相：前 `L` 个动作算主损失；尾部用 hold/retreat/减速作为辅助目标；避免“接触时继续猛推”。
- 如果 `L` 由相位头预测，加一个 `L` 的辅助损失（可选）。

#### 3.4.4 损失

```
L = L_action + λ_phase·L_phase + λ_progress·L_progress + λ_imp·L_imp
L_imp = max(0, J_norm − B_task)^2   （只作用在接触相）
```

- `L_action`：flow matching / L1 / L2（按基座）。
- `L_phase`：6 类 CE。
- `L_progress`：轻量步骤进度头（只用于恢复，不用于刷步骤分）。
- `L_imp`：冲量代理越界惩罚；同时惩罚接触相加速度/加加速度。

#### 3.4.5 验证

- 按 session/robot/date 切分；不按帧随机切。
- 延迟扫描 `d ∈ {0,2,4,8,12,16,20}`；报告 success、phase accuracy、`J_norm`、recovery。
- 门控：d=8 时比无延迟训练 +5 pp；d=0 不降；接触相 `J_norm` 不升。

### 3.5 AURA-32

#### 3.5.1 定义

| 维度 | 指标 | 定义 |
|---|---|---|
| Availability | p50/p99 延迟 | 每步 `get_action` 端到端 |
| Availability | 抖动 | p99−p50 |
| Availability | deadline miss | `C > C_budget` 的比例 |
| Availability | 端口隔离 | N 并发下无串扰/无相互阻塞 |
| Usability | `U(τ)` | `P(success ∧ T≤τ ∧ no safety event)` |
| Usability | `S(τ)` | `E[step_score·1(T≤τ)]` |
| Usability | AURA-AUC | `(1/τ_max)∫U(τ)dτ` |
| Recovery | `R(τ)` | 偏离后 τ 秒内恢复的概率 |
| Assurance | `J_norm` 越界 | 每 100 次试验 |
| Assurance | 不可逆失败 | 掉落/碰撞/卡死/需复位 |
| Assurance | 动作离群 | chunk 边界跳变/速度/加速度越界 |
| Assurance | 协议违规 | token/shape/端口；应为 0 |

τ 网格：5/10/20/30/60/180 s。

#### 3.5.2 测量协议

1. 每个任务/轴记录：success、step score、time-to-success、`J_norm`、失败阶段、失败类型。
2. 延迟：每步打点；报告 p50/p99/抖动；按端口分组。
3. 恢复：在调试通道注入 deviation（物体移动/抓取滑落/插入卡住/拉链回退）；记录 `R(τ)`。
4. 安全：所有不可逆事件单独计数；不与 success 混在一起。
5. 报告：总体 + 每轴 + 任务族；单任务 n=10 只给 CI，不做强结论。

#### 3.5.3 统计功效

| 样本量 | SE（p≈0.3） | 用途 |
|---:|---:|---|
| 320 | 2.56 pp | 总体 |
| 64 | 5.73 pp | 每轴 |
| 10 | 14.49 pp | 每任务 |
| 2 | 32.4 pp | 每任务每轴 |

**规则**：任何小于 1.5×SE 的差异都不叫“提升”；AURA 曲线要给 bootstrap CI。

### 3.6 N 端口服务

#### 3.6.1 架构

**Approach 1：process-per-port**

- 每个端口一个进程，各自加载模型；隔离最好，显存 N 倍。
- 适合 N 小、模型小、显存足。

**Approach 2：shared backend**

- N 个轻量 endpoint + 一个共享推理后端；continuous batching；per-port 状态。
- 适合 N 大、模型大；必须做状态隔离与 deadline 调度。

#### 3.6.2 调度

- 每个请求有 deadline：`deadline = 上次 chunk 开始执行 + C_budget`。
- EDF（earliest deadline first）；batch 里混不同端口的请求；避免一个慢端口阻塞所有端口。
- 不同机器人消费 chunk 的速率不同（Armory）；按端口维护 `T_a`/消费速率，不要假设同构。
- 如果队列等待 > budget：watchdog 返回 hold/retreat，记录回退率。

#### 3.6.3 状态隔离

- 每端口独立：episode id、obs history、phase、belief、L、last action、token 校验。
- 禁止共享可变 history；模型权重可共享，KV/缓存不可跨端口。
- `reset()` 必须清空该端口所有状态；并发 reset 不能影响其他端口。
- 压测：N ∈ {1,2,3,4,6,8}，检查串扰、p99、抖动、deadline miss。

#### 3.6.4 工程

- warmup、CUDA graphs、FP8/INT8、图像 resize、pinned memory、零拷贝。
- 预处理/后处理与模型解耦；避免每步重新分配大 tensor。
- 延迟遥测：每步记录 `t_request/t_model/t_post/t_response`；按端口聚合。
- 失败回退：模型异常/超时 → 安全 hold/retreat；不要返回 NaN/越界动作。

## 4. 数据 pilot：两种接触时间尺度

### 4.1 定义

对每个任务的首个 parquet（非全量）做探索性分析：

- 开合基线：每 episode/侧的 95th percentile。
- 闭合事件：`action_gripper < baseline − 0.5` 的连续段；合并间隔 <0.3 s 的段。
- `T_t`：从事件开始到首次达到闭合平台（最小值 +0.1）的时间。
- `T_h`：从平台到事件结束（命令回升 > 最小值 +0.5）的时间。
- 保持占比：`T_h` 帧数 / episode 帧数。

这是启发式定义，不是官方标注；只用于提出“两种时间尺度”的假设。

### 4.2 结果

| 任务 | 侧 | 事件数 | `T_t` 中位 | `T_t` p90 | `T_h` 中位 | `T_h` p90 | 保持占比 |
|---|---|---:|---:|---:|---:|---:|---:|
| HangCup | 右 | 781 | **0.27 s** | 0.70 s | **3.13 s** | 4.33 s | 56.7% |
| FoldTowel | 左 | 357 | **0.37 s** | 2.51 s | **4.50 s** | 11.02 s | 49.2% |
| FoldTowel | 右 | 404 | **0.37 s** | 0.96 s | **3.32 s** | 11.49 s | 50.3% |
| PlugCharger | 左 | 416 | **0.07 s** | 0.40 s | **8.17 s** | 11.87 s | 64.5% |
| PlugCharger | 右 | 290 | **0.27 s** | 0.30 s | **6.20 s** | 9.81 s | 43.1% |

（HangCup 左臂只有 4 个事件，未列入；FoldTowel 的长尾来自多次抓取和可变形操作。）

### 4.3 解释

- `T_t` 中位 0.07–0.37 s；`T_h` 中位 3.13–8.17 s。两者差 **一个数量级以上**。
- 若 `τ=100 ms`、`T_a=6`（C=300 ms）：`ρ_t ≈ 0.23–1.23`，`ρ_h ≈ 10–27`。也就是说：**瞬态和 C 同量级，保持远长于 C**。
- 因此：
  - 瞬态不能靠“等下一次观测”来闭环；必须前馈柔顺 + 冲量预算。
  - 保持相可以闭环/探测；CBP 有足够时间收敛。
  - 一个全局固定 `T_a` 不能同时优化两者；需要 `L` 和相位/时间尺度自适应。

### 4.4 局限

- 只分析了 3 个任务的首个 parquet（719/142/269 episodes），不是全量 32 任务。
- 夹爪阈值/事件合并是启发式的；`T_h` 对多抓任务（FoldTowel）会偏长。
- 没有视觉接触标签，`T_t` 是“夹爪闭合瞬态”，不是严格力学接触时间。
- 结论只用于提出假设；E2 要在全量数据上复核，并用人工审计校准。

## 5. 实验设计

### 5.1 E1：时序语义与 `T_a` 扫描

**问题**：官方是同步还是流水线？`C` 是否符合 `τ+T_a·Δt`？

**设计**：

- 在 `get_action` 入口/出口打 `time.monotonic_ns`；记录每次 obs 的时间戳、返回 chunk 的时间、下一次调用的时间。
- 单任务调试通道；扫 `T_a ∈ {1,2,3,4,6,8,12,16,24,32,50}`。
- 同时测 `τ` 的 p50/p99/抖动；网络 RTT 单独记录。
- 用一个固定策略（例如 replay 或简单 BC）避免模型差异干扰。

**指标**：实测 `C`、占空比、成功率、步骤分、动作抖动（chunk 边界加速度）、deadline miss。

**门 G1**：确认 `C` 公式；选出 Pareto `T_a`；若同步式成立，记录 `C_budget`。

### 5.2 E2：32 任务时间尺度估计

**问题**：`T_t/T_h` 是否跨 session 稳定？任务能否按时间尺度分组？

**设计**：

- 全量 32 parquet；夹爪事件 + 视觉接触弱标签；每任务至少 50 个事件。
- 分层贝叶斯收缩：任务级 → 任务族级；避免小样本任务噪声。
- 人工审计 160 段（每任务 5 段）校准阈值。

**指标**：`T_t/T_h` 中位、p90、保持占比、跨 session 变异。

**门 G2**：任务族可分；跨 session 的中位差异 < 2×；否则只按任务族用，不按单任务。

### 5.3 E3：DCCT 离线训练

**问题**：延迟条件训练能否在 d=8 时提升，且 d=0 不降？

**设计**：

- 基座：3B–6B VLA + LoRA；4 相机；图像 resize；action chunk。
- 延迟增广 `d ~ U{0..20}`；20% d=0；latency token；prefix-tail；contact weighting；`L_imp`。
- Session-grouped split；延迟扫描 d ∈ {0,2,4,8,12,16,20}。
- 基线：无延迟训练、TT-RTC 式训练（无接触项）、第 10 轮 FACT-VLA。

**指标**：success、phase accuracy、`J_norm`、recovery、动作平滑度。

**门 G3**：d=8 时 +5 pp；d=0 不降超过 1 pp；接触相 `J_norm` 不升。

### 5.4 E4：CTAC 运行时消融

**问题**：IBCC/CBP 是否在快瞬态/长保持任务上分别有效？

**设计**：

- 快瞬态：HangCup、ZipUp 起拉；长保持：PlugCharger、Unlock、Syringe；慢接触：FoldTowel。
- 消融：无 CTAC、只有 IBCC、只有 CBP、IBCC+CBP、固定 L。
- 真机调试通道，每任务 10 次；记录失败阶段/类型。

**指标**：success、`J_norm`、不可逆失败、`R(τ)`、time-to-success。

**门 G4**：快瞬态 +5 pp；长保持不降；不可逆失败不升；`R(τ)` +10 pp（若有偏离注入）。

### 5.5 E5：N 端口压测

**问题**：N 并发下是否 p99 达标、无串扰？

**设计**：

- 用固定延迟的 dummy 策略 + 真实模型两套；N ∈ {1,2,3,4,6,8}。
- 每端口独立 episode；随机 reset；注入慢请求/网络抖动。
- 对比 process-per-port vs shared backend + EDF。

**指标**：每端口 p50/p99、抖动、deadline miss、回退率、串扰（状态哈希）、总吞吐。

**门 G5**：p99 < `C_budget`；deadline miss <1%；无状态泄漏；回退率 <1%。

### 5.6 E6：真机非劣与安全

**问题**：TACT 是否在真机上非劣，且冲量/恢复更好？

**设计**：

- 3 任务（HangCup 快瞬态、PlugCharger 长保持、FoldTowel 慢接触）×10 次。
- 对比第 10 轮 FACT-VLA；同一基座、同一数据、同一 `T_a` 扫描。
- 记录 `J_norm`、不可逆失败、恢复事件。

**门 G6**：success 非劣（CI 下界 > −5 pp）；`J_norm` 更低；`R(τ)` 更高；无不可逆失败增加。

### 5.7 E7：全量 dry run

**问题**：32×10 是否稳？AURA 是否可报告？

**设计**：

- 32 任务 ×10；5 轴 ×2；单模型；N 端口。
- 预注册分析：success、step score、AURA、失败分类。
- 顺序检验：先看总体，再看任务族，最后看单任务；单任务只给 CI。

**门 G7**：无安全/协议事件；step score 不倒退；AURA 不低于基线。

### 5.8 资源与时间线

| 阶段 | 时间 | 资源 | 产出 |
|---|---:|---|---|
| E1/E2 | 1–2 周 | 1×A100 + 调试通道 | `C` 公式、`T_a` 表、`T_c` 表 |
| E3 | 3–4 周 | 4×A100 80GB；3B–6B + LoRA | DCCT checkpoint |
| E4/E5 | 2 周 | 4×A100 + N 端口 | CTAC/AURA 结果 |
| E6/E7 | 2–3 周 | 真机调试 + 全量 | 提交候选 |

**训练粗估**：18.3M 帧、4 相机；每 episode 采样 64–128 帧；batch 64；2 epochs；4×A100 约 2–3 周/轮。若显存/时间不够，先做 224×224、每 episode 64 帧、LoRA；不要一上来全参。

### 5.9 消融清单

- LMC：固定 `T_a` vs 膝点 `T_a`；固定 L vs 相位 L。
- DCCT：无延迟 vs 延迟；无 latency token vs 有；无 prefix-tail vs 有；无 `L_imp` vs 有。
- CTAC：无 IBCC vs 有；无 CBP vs 有；快/长/慢三区。
- AURA：只报 success vs 报 AURA；有无 watchdog。
- 服务：process-per-port vs shared；EDF vs FIFO；有无状态隔离。

## 7. 风险、合规与开放问题

### 7.1 风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 官方其实是流水线调用 | 中 | 高 | E1 时间戳；LMC 两套公式；不把同步式写死 |
| 无力传感器，`J_norm` 不可校准 | 高 | 中 | 只用相对排序 + 保守上限；用安全事件校准；不声称牛顿 |
| 接触相位标签噪声 | 高 | 中 | 夹爪/视觉弱监督 + 160 段人工审计；软标签 |
| `T_t/T_h` 跨任务不稳 | 中 | 中 | 分层收缩；任务族聚合；不按单任务下结论 |
| N 端口共享后端串扰 | 中 | 高 | per-port 状态、隔离测试、watchdog、process-per-port 兜底 |
| 单模型约束 | 低 | 中 | 一个 checkpoint + 相位/延迟条件；不切模型 |
| 榜单种子数据误导 | 高 | 中 | 不把排行当难度表；以调试通道和自测为准 |
| 规则修订 | 低 | 高 | 全量提交前重读 Feishu/README；合规检查表 |
| 训练成本超预算 | 中 | 中 | LoRA + 224×224 + 每 episode 64 帧；先 E1/E2 再 E3 |

### 7.2 合规检查表

- [ ] 单模型完成全部 32 任务；没有 per-task 模型切换。
- [ ] `metadata` 的 `control_space`、`obs_delta_indices`、`image_resize`、`action_chunk_size`、`token` 与 README 一致。
- [ ] 每次 `get_action` 返回 `meta.token`；shape/dtype 正确；无 NaN/Inf。
- [ ] N 个连续端口；每端口独立 `reset`/history；并发无串扰。
- [ ] 不依赖测试时 best-of-K/多候选搜索；延迟平滑；动作良构。
- [ ] 无外部网络调用/隐藏服务；所有推理在选手自部署服务内。
- [ ] 不把公开榜单/任务卡当唯一依据；全量前重读规则。
- [ ] 安全回退：超时/异常 → hold/retreat；不执行不可逆动作。

### 7.3 开放问题

1. evaluator 是否执行完整 `T_a` 后再调用，还是执行前缀就提前调用？E1 回答。
2. 控制频率 `Δt` 是 30 Hz 还是别的？E1 实测。
3. `action_chunk_size` 是否允许 per-port 不同？README 说是 metadata 固定；按全局处理。
4. 评测端是否允许尾部 hold/retreat 动作？动作是位置目标，应该允许；需在调试通道验证。
5. N 的确切数值？官方另行公布；服务要能配置。
6. 失败/成功信号是否可被策略观测？若不可，恢复只能靠视觉/接触信念。
7. 官方是否把延迟/抖动用于排名或可信度判断？§6 说“可能展示/评估”，按硬约束处理。
