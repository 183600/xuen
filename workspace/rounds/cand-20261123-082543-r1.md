# 第 1 轮（灵感驱动研究循环·新循环第 1 轮；本轮灵感：「工具调用」×「抓取」）

> **基线**：上一轮产出 MetricVoiceGauge-NCD-HUTDH-v21+IP-425–430（语义-合规层；其上承 v20 联邦感知证书、v19 证书体系 DCM/OGCC/CCV/DRS/OGC、v17 感知链 CLP/S2C/HCG/PSV/APS/AMC）。
> 本轮纪律：**行动是带类型的、可授权的能力调用（规划器提议、运行时处置）；抓取是被许可引入的、力闭合有界的接触**。不推倒 v21：SDC/CAC/DCL/GIC/HPC+/CFC+ 全部保留，v20/v19/v17 各模块全部保留。本轮只做一件事：**在 v21 的"语义-规范"层之上加一层"能力-接触"层，把"这条运动是否安全"升级为"这次动作是否被授权执行一个有界契约、并携带全部新鲜证书"，并把"抓取"实现为该层的第一个物理能力**。

## 0. 直觉与动机

**灵感 1（工具调用 → 行动即类型化能力调用，规划器提议、运行时处置）**
直觉：v21 能证明"这条运动安全"，却无法回答"**谁**在**什么授权**下、对**哪个对象**、以**什么参数**执行**哪个能力**"。现代 agent 的工具调用给出了成熟范式：模型输出结构化调用 `f(args)`，由可信运行时做 **schema 校验 → 权限检查 → 沙箱执行 → 结果回填**，并配幂等键、超时、dry-run、回滚。关键反直觉点：**v21 的证书体系本质上就是一个行动的"类型系统"**——HPC+ 是运动参数的类型，CC/AbsCert 是细化类型，DCL 是效果系统；一次工具调用之所以"类型正确"，正因为它把所需证书作为**参数**随身携带、且在**调用时**新鲜（而非签发时新鲜）。由此引入 **能力租约 (Capability Lease, CapCert)**：作用域受限、带过期、带 nonce（不可重放）、可衰减委派（scope 只能缩不能扩）的授权令牌。核心安全论点是：**规划器可以不可信（幻觉、被注入、被攻破），运行时必须可信——证书系统把不可信规划器的爆炸半径限制为"已租出能力的并集"**。

**灵感 2（抓取 → 接触是被许可引入的障碍，抓取证书把"无碰撞"升级为"有界力闭合接触"）**
直觉：v20/v21 是**避碰**证书，接触一律是坏事；但抓取的全部意义就是接触。于是证据单调律需要一个第三原语：**接触不是默认安全，而是必须被"租"出来**。一次抓取可采纳当且仅当：(a) 接近/撤离路径 ∈ v21 HPC+（无碰撞）；(b) 在**位姿 × 摩擦 × 质量不确定集 U** 上**鲁棒力闭合**（`ε*(G,U) = min_{δ∈U} ε(G_δ) ≥ ε_min`，其中 ε 为 Ferrari–Canny 度量）；(c) 接触力 `‖f‖_∞ ≤ F_max` 且滑移概率 ≤ δ_slip；(d) **对象身份被证书接地**（复用 v21 SDC 的 CertBox + CTS 先验：抓的必须是声明的那一个，而不是"长得很像"的物体或人的手）；(e) 后置条件（抬起高度/力签名/视觉位姿）被验证，否则**受控释放 + 回退**。关键反直觉点：**抓取与缺席证书是对偶的**——自由空间必须被缺席证书"赎回"，接触必须被抓取证书"租出"；两者默认都是"不允许"，只是一边靠负信息释放空间，另一边靠正信息释放接触。失败的抓取必须 fail-safe：滑移 → 在力上限内升力 → 仍滑则受控释放并撤离，**绝不超限硬捏**。

**两者如何统一（租约代数）**
CapCert 是"对能力的租约"，GC/CCt 是"对接触的租约"，两者同构：`lease = (scope, bounds, expiry, nonce, attenuation, audit)`。统一为 **v22 能力-接触层 (Capability-Contact Layer)**，共享状态扩展为 `ζ_cap = ζ_sem ∪ (cap_registry, active_leases, call_graph, contact_state)`。统一准入门 **HPC++**：`admit(call) ⇔ schema_ok ∧ CapCert_ok ∧ cert_args 调用时新鲜 ∧ Pre(ζ) ∧ dry_run(真实 Eff ⊆ 声明 Eff) ∧ (contact ⇒ GC_ok)`。任何一步失败 → 不执行或回退，退化为 v21 的纯运动。多机器人下能力可**衰减委派**（A 租给 B，则 `scope(B) ⊆ scope(A)`、`bounds(B) ⊆ bounds(A)`），调用图必须**无环**（有环即拒绝），呼应并封堵 v21 的义务死锁风险。

## 1. 研究问题（轮次升级版）

- **Q1（调用的类型健全性）**：如何定义 `Γ; ζ ⊢ call : ok`，使"被采纳的调用"其真实效果 ⊆ 声明效果 `Eff`，且后置条件要么被验证、要么回滚到 `rollback_state`？证书参数（HPC+/CC/AbsCert/GC）如何以类型方式强制"**调用时**新鲜"而非"签发时新鲜"？dry-run 对含物理接触的调用能预测到什么精度？

- **Q2（租约的最小权限与不可重放）**：CapCert 的 `scope / arg_bounds / expiry / nonce` 如何联合保证不可重放、不可提权、可审计？衰减委派 `scope(B) ⊆ scope(A) ∧ bounds(B) ⊆ bounds(A)` 在什么条件下保持安全继承？分布式多机器人下 nonce 与时钟偏移如何不产生"幽灵租约"？

- **Q3（鲁棒力闭合与不确定集）**：如何在 `U = U_pose × U_fric × U_mass` 上高效计算 `ε*(G,U) = min_{δ∈U} ε(G_δ)`？`ε_min` 与 v21 的 `ε_loc`、`margin_col_fed`、`τ_consensus` 如何统一标定而互不破坏？摩擦/刚性模型被现实违反时，"滑移检测 → 力上限内升力 → 受控释放撤离"如何保证**不捏碎、不摔落**？

- **Q4（身份接地与后置验证）**：如何用 v21 SDC 的 CertBox + CTS 谱系先验做**实例级**身份证明 `id_proof`，使"抓错对象/抓到手"在证书层被拒绝？后置条件（抬起高度/力签名/视觉位姿）如何低成本验证？物理动作执行到一半时的**部分回滚**如何定义与审计？

## 2. 设计原则（在 P34–P36 基础上新增 P37–P39）

**P37 调用类型健全律（Tool-Call Type Soundness）**
每个能力建模为 `κ = (X, Pre, Post, Eff, C_req, R)`。调用 `c = (κ, x, certs, nonce, τ_exp)` 被采纳当且仅当：`x ∈ X`（schema 校验，含工具白名单拒绝幻觉工具）∧ `CapCert_ok` ∧ `certs ⊇ C_req(κ)` 且**调用时**新鲜 ∧ `Pre(ζ, x)` ∧ DCL 允许 ∧ `dry_run` 证明 `Post` 可达且真实 `Eff ⊆ Eff`。执行后必须产出 `ContCert`（`Post` 验证通过）**或**回滚到 `rollback_state`。**未被采纳的调用不产生任何效果**（拒绝即无副作用）。

**P38 租约最小权限律（Least-Authority Leases）**
CapCert 与 GC 均为 `(scope, bounds, expiry, nonce, sig)`；作用域只缩不扩（衰减委派 `scope_child ⊆ scope_parent`），过期即失效，nonce 一次性（重放拒绝），参数越界即拒绝。故任何（含被注入/幻觉/被攻破的）规划器可达效果 ⊆ ⋃ 已租出能力之并集；跨机器人调用图必须无环，否则拒绝并回退。

**P39 接触租约与力界律（Contact-Lease & Force-Bound）**
默认非接触；接触仅当持有有效 GC 且 `ε*(G,U) ≥ ε_min ∧ ‖f‖_∞ ≤ F_max ∧ P(slip) ≤ δ_slip ∧ id_proof 有效` 时被允许，且接触区域限于 GC 声明的对象区域（"接触租约"到期或滑移即撤销）。滑移 → 在 `F_max` 内升力 → 仍滑则受控释放并撤离（回退），禁止超限硬捏。故 `Exec_v22 = {plan ∈ Exec_v21 : 无接触 ∨ 接触 ⊆ 有效租约} ⊆ Exec_v21`。

## 3. 与基线的接口（如何退化）

- CTI/TCR 失效（注册表/运行时崩溃）⇒ 只能执行 v21 已认证的纯运动，无任何能力调用 ⇒ 等价 v21（更保守）；
- CapCert 失效（授权服务不可用）⇒ 无授权 ⇒ **默认拒绝全部调用**（fail-safe 方向）；
- GC 失效或身份不可证 ⇒ 不接触 ⇒ 退化为 v21 纯运动（不抓），安全继承不变；
- 摩擦模型失准但 SRC 在线 ⇒ 滑移检测 → 受控释放，最坏结果为"没抓成"，不为"捏碎/摔落"；
- 委派环/资源死锁 ⇒ 调用图静态无环检测 + 租约超时回退 ⇒ 无死锁；
- 全失效 ⇒ 完全回退 v21 ⇒ `Exec_v22 ⊆ Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19 ⊆ Exec_v18`（引理 168）。
- **安全继承**：调用只能复用 Exec_v21 的运动 + 租约内的接触；任何失效都向"不执行 / 不接触 / 回退"方向退化。租约新鲜度接入 v17 APS 阶梯，控制路径仅做 O(1) 租约查询。

## 4. 预期贡献

1. **行动即类型化能力调用**：把 v21 证书体系显式化为行动的"类型系统"，给出 `Γ; ζ ⊢ call : ok` 的类型健全性（真实效果 ⊆ 声明效果，后置失败必回滚）；
2. **能力租约**：作用域 + 参数界 + 过期 + nonce + 衰减委派的统一最小权限模型，使**不可信规划器的爆炸半径 ≤ 已租出能力并集**；
3. **鲁棒抓取证书**：在 `U_pose × U_fric × U_mass` 上定义 `ε*(G,U)`，把"无碰撞"升级为"有界力闭合接触"，并给出滑移回退的 fail-safe；
4. **身份接地**：用 SDC CertBox + CTS 先验做实例级 `id_proof`，把"抓错对象/抓到手"在证书层拒绝，兼作 v21 人体召回风险的又一道独立护栏；
5. **接触与缺席的对偶**：自由空间靠缺席证书赎回、接触靠抓取证书租出，统一"默认不允许、需证据释放"的证据哲学；
6. **能力-接触门 HPC++**：`Exec_v22 ⊆ Exec_v21` 闭环，且多机器人委派无环、无死锁。

## 5. 本轮最大风险

**一句话**：整个能力-接触层把安全押在"契约前置条件/效果完备"与"摩擦/刚性模型正确"这两个**不可观测的元假设**上——形式验证只证明"相对于契约安全"，而契约对现实的不完备（可变形/湿滑物体、被误识别的目标、未声明的副作用）无法被系统内部证伪，于是机器人会**类型正确地、审计通过地、力闭合达标地**抓碎或抓错（最坏：把人手当成目标物体）。

# IP-431 Capability Tool Interface：能力即带类型的契约
@dataclass
class Capability:
    id: str
    X: TypeSpec            # 参数空间（含类型与取值域）
    Pre: Predicate         # Pre(zeta, x)
    Post: Predicate        # Post(zeta_prime, x, result)
    Eff: EffectEnvelope    # 声明效果：motion / contact / resource
    C_req: frozenset       # 所需证书类型 {HPC+, CC, AbsCert, GC}
    R: ResourceScope

class CapabilityRegistry:
    def get(self, cap_id):
        return self._table.get(cap_id)        # 白名单：不存在即幻觉工具
    def validate(self, call):
        cap = self.get(call.cap_id)
        return cap is not None and cap.X.accepts(call.x)


# IP-432 Capability Certificate：作用域受限、一次性、可衰减的租约
@dataclass
class CapCert:
    id: str; cap_id: str; arg_bounds: TypeSpec
    scope: ResourceScope; t_exp: float; nonce: str; sig: str
    consumed: bool = False

    def valid(self, call, t_now):
        return (call.cap_id == self.cap_id
                and self.arg_bounds.contains(call.x)
                and t_now <= self.t_exp
                and call.nonce == self.nonce
                and not self.consumed)        # nonce 一次性 → 不可重放

def attenuate(parent: CapCert, child_scope, child_bounds, ttl) -> CapCert:
    assert child_scope <= parent.scope and child_bounds <= parent.arg_bounds
    return CapCert(id=new_id(), cap_id=parent.cap_id,
                   arg_bounds=child_bounds, scope=child_scope,
                   t_exp=min(parent.t_exp, now() + ttl),   # 只缩不扩
                   nonce=new_nonce(), sig=sign(parent.sig, child_scope))


# IP-433 Tool-Call Runtime：规划器提议、运行时处置
class ToolCallRuntime:
    def __init__(self, registry, hpc_gate, dcl, aps):
        self.reg, self.gate, self.dcl, self.aps = registry, hpc_gate, dcl, aps

    def admit(self, call, zeta, t):
        if not self.reg.validate(call):            return False, "SCHEMA"
        if not call.capcert.valid(call, t):         return False, "LEASE"
        if not self._certs_fresh(call, t):          return False, "STALE_CERT"
        if not call.cap.Pre(zeta, call.x):          return False, "PRECOND"
        if not self.dcl.allows(call, zeta):         return False, "DEONTIC"
        if not self._acyclic(call):                 return False, "CALL_CYCLE"
        post_ok, eff = self.simulate(call, zeta)    # dry-run
        if not post_ok or not eff <= call.cap.Eff:  return False, "DRYRUN_EFFECT"
        return True, "OK"

    def execute(self, call, zeta):
        ok, why = self.admit(call, zeta, call.t)
        if not ok:
            return Rejected(why)                    # 拒绝即无副作用（P37）
        snap = snapshot(zeta)                       # rollback_state
        result = self._sandboxed_run(call)          # 隔离执行
        if call.cap.Post(zeta, call.x, result):
            return ContCert(call.id, True, observe(result), snap)
        self._rollback(snap)                        # 后置失败 → 回退
        return ContCert(call.id, False, observe(result), snap)


# IP-434 Grasp Certificate：鲁棒力闭合 + 力界 + 身份接地
class GraspCertifier:
    def __init__(self, sdc, cts, eps_min=0.05, F_max=40.0, delta_slip=0.01):
        self.sdc, self.cts = sdc, cts
        self.eps_min, self.F_max, self.delta_slip = eps_min, F_max, delta_slip

    def issue(self, grasp, U, detections):
        idp = self.sdc.identity_proof(grasp.o_id, grasp.region, detections)
        if not idp.valid:                           # 抓错/抓到手 → 拒发
            return None, "IDENTITY_UNGROUNDED"
        eps_star = min(self._epsilon(grasp, delta) for delta in sample(U))
        if eps_star < self.eps_min:                 # 不鲁棒力闭合 → 拒发
            return None, "NO_ROBUST_FC"
        if not self._force_bounded(grasp, self.F_max):
            return None, "FORCE_OVER"
        return GC(grasp, eps_star, self.F_max, self.delta_slip, idp, U, now())

class SlipRollbackController:
    def __init__(self, gc, tactile, force_limiter):
        self.gc, self.tactile, self.limiter = gc, tactile, force_limiter
        self.f = gc.initial_force

    def step(self, sensed):
        if self.slip_prob(sensed) > self.gc.delta_slip:      # 检测到滑移
            if self.f < self.gc.F_max:
                self.f = min(self.f * 1.2, self.gc.F_max)    # 力上限内升力
                return escalate_force(self.f)
            return controlled_release_then_retreat()         # 绝不超限硬捏
        return hold()


# IP-436 HPC++：能力-接触门（v21 HPC+ 原样保留，只加租约与接触门）
@dataclass
class HPCPlusPlus:
    hpcp: HPCPlus                 # v21 三证一体（几何∧规范∧负信息）
    capcert: CapCert              # 能力租约
    contcert: ContCert | None     # 契约履行证书
    gc: GC | None                 # 接触租约（无接触可为 None）

    def admits(self, call):
        return (self.capcert.valid(call, now())
                and self.hpcp.admits(call.motion_theta)
                and (not call.introduces_contact
                     or (self.gc is not None and self.gc.valid()
                         and self.gc.region.contains(call.contact_region))))

## 3. 推导

**引理 163（工具调用类型健全性）** 若 `Γ; ζ ⊢ c : ok`，则 `_sandboxed_run` 的真实效果 ⊆ `Eff(κ)`，且执行结果满足 `ContCert.post_ok` 或已回滚到 `rollback_state`。证明：`admit` 的 schema/Pre/dry-run 保证 `Post` 在 ζ 上可达且预测效果 ⊆ 声明效果；`execute` 执行后强制验证 `Post`，失败即回滚；拒绝分支在 `_sandboxed_run` 之前返回，故无副作用。∎

**引理 164（租约最小权限与不可重放）** CapCert 的 `scope / arg_bounds / expiry / nonce` 均为单调约束，且 `attenuate` 强制 `scope(B) ⊆ scope(A) ∧ bounds(B) ⊆ bounds(A)`，故委派链上任意子租约可达效果 ⊆ 父租约；nonce 一次性 ⇒ 重放被拒；越界/过期 ⇒ 拒绝；调用图无环检测 ⇒ 跨机器人互调不成环。于是任意（含被注入/幻觉/被攻破的）规划器可达效果 ⊆ ⋃ 有效租约能力并集。∎

**引理 165（鲁棒力闭合与滑移回退）** 若 `ε*(G,U) ≥ ε_min > 0` 且 `‖f‖_∞ ≤ F_max`，则对 U 内任意位姿/摩擦/质量实现，抓取力闭合且不超力界。当真实参数 `δ ∉ U` 或摩擦模型错误时，SRC 由触觉滑移检测在 `δ_slip` 预算内触发：`f < F_max` 时升力，仍滑则受控释放并撤离。故最坏结果为"未抓成"，而非"捏碎/摔落"（前提：触觉可观测滑移）。∎

**引理 166（身份接地阻断错抓）** 若 `id_proof` 要求 SDC 实例级匹配（类别一致 ∧ 实例置信 ≥ θ ∧ CertBox 覆盖抓取区 ∧ CTS 先验一致）且 v21 CAC 手势/在场条款未翻转，则"抓到手/抓错近似物"因 `IDENTITY_UNGROUNDED` 被拒发；无 GC ⇒ `introduces_contact` 的调用不可采纳 ⇒ 不接触。∎

**引理 167（接触-缺席对偶）** v21 中自由空间仅由 AbsCert 赎回；v22 中接触仅由 GC 租出。二者都是"默认不允许、需证据释放"的单调证据系统：AbsCert 用负信息释放空间、GC 用正信息（鲁棒力闭合+身份）释放接触。故接触引入不扩张 v21 的自由空间假设，只在其已认证的几何域内加入有界接触，`Exec_v22` 的接触部分 ⊆ v21 几何域。∎

**引理 168（v22 整体安全继承）** 调用只复用 Exec_v21 运动（HPC+，引理 162）、接触仅限有效 GC 区域（167）、委派只缩不扩（164）、后置失败必回滚（163）。故 `Exec_v22 ⊆ Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19 ⊆ Exec_v18`。∎

## 7. 已知风险与失效模式

1. **契约完备性幻觉**（最大风险，见第 8 节）：Pre/Eff 对现实的遗漏无法被系统内部证伪。缓解：E826 红队删条目测检出率、运行时效果监控（E802）、契约 lint 与形式化审查。
2. **摩擦/刚性模型失配**：真实 μ 低于假设或物体可变形 → 力闭合形式成立而实际滑移/压碎。缓解：U 保守下界、在线物理辨识（E809）、SRC 滑移回收（E811/E812/E827）。
3. **身份接地依赖检测器**：承接 v21 召回风险，目标被误识别（尤其人手）→ 错抓。缓解：`id_proof` 实例级匹配 + CAC 手势在场联动（E814）+ 人手专用通道。
4. **租约分布式一致性**：nonce 重放、时钟偏移、分区导致"幽灵租约"。缓解：单次 nonce + 短 TTL + 单调时钟/租约 fencing token（E803）。
5. **委派提权/调用环**：跨机器人委派越权或互调成环。缓解：衰减类型系统 + 无环静态检测 + 超时回退（E804/E817）。
6. **部分回滚不可逆**：物理动作执行一半难以完全回滚。缓解：接触前多设可回退检查点、受控释放为默认回退、回退只保证"安全态"而非"原态"（E807）。
7. **隐私成本**：抓取处理图像/触觉等生物特征。缓解：沿用 v21 数据最小化，原始数据不出设备，仅传证书与几何/力特征（E794 延续）。

## 8. 本轮最大风险

**一句话**：整个能力-接触层把安全押在"契约前置条件/效果完备"与"摩擦/刚性模型正确"这两个**不可观测的元假设**上——形式验证只证明"相对于契约安全"，而契约对现实的不完备（可变形/湿滑物体、被误识别的目标、未声明的副作用）无法被系统内部证伪，于是机器人会**类型正确地、审计通过地、力闭合达标地**抓碎或抓错（最坏：把人手当成目标物体）。
