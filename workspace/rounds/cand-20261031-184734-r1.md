# 第 13 轮（新灵感循环第 1 轮）· UNDERWRITER：不卖模型，卖可兑现的成功率——把 33k 演示变成开放词汇技能库，把每次 trial 当成一份保单

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是灵感循环第 1 轮，三个词是「商业模式」「开放词汇」「成功率」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO；它给 CHUNK-SERVO 加一个此前没有的决策层：**这次尝试值不值得继续？如果继续，应该押哪个技能变体？如果失败，什么时候止损、什么时候回溯？**

## 0. 先给结论：成功率不是模型属性，而是一次可以被承保的决策

截至 2026-10-31，官网榜单仍是 8 个模型的“合成预览”：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。`leaderboard_data.json` 仍标注 `generated_from=gen_leaderboard.py`，`step≈k_model×success` 的 R²>0.999999，详情页/runs 页仍是占位视频。**29.7% 是预览上限，不是可复现 SOTA，也不是失败分布。** 但它给出一个有用的信号：在 320 次真机 trial 里，成功是稀缺事件，绝大多数 trial 会在某个阶段走向失败。

现有 VLA 的默认策略是“把 30 步 chunk 全部执行完，再等下一次观测”。这是一种**无条件履约**：不管当前状态是否已经偏离，不管这个技能是否匹配，不管剩余时间够不够重试，都继续执行。问题不是模型不会预测动作，而是**没有人在执行前和执行中问一句：这份“成功承诺”还值多少钱？**

所以本轮押注 **UNDERWRITER**：

> 用 33k 成功演示离线构造「开放词汇技能卡」；在线用同一 VLA checkpoint 的多次采样/语言改写/几何可行性，给每个技能变体开一张**无训练的成功率证书**；再用一个“承保策略”选择技能、决定是否继续、何时止损/回溯，把 180 秒和 GPU 算力当成保费，最大化**每次尝试的期望成功数**。不加第二个学习策略。

一句话：**不要问“模型能不能做”，要问“这次尝试值不值得承保”。**

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **商业模式** | 把 trial 当保单：技能卡是产品，成功率证书是核保，abort/retry 是止损，失败日志是理赔，单任务通道是再保险；优化“每 GPU-小时的成功数” | 不写商业计划书；不跳过任务挑简单的做；不把竞赛规则改成竞价 |
| **开放词汇** | 技能卡按「动词 + 目标 affordance + 受器 affordance」索引，不按 32 个 task ID；语言改写/同类新外观走同一张卡；不会就回退 VLA 并记账 | 不假设“未见物品”是全新类别；不让外部 VLM/检测器成为第二个模型；不声称开放世界 |
| **成功率** | 预执行证书 + 执行中证书；用计划一致性、演示支持度、几何/运动学可行性、目标可见性做无训练打分；用分位数/置信下界校准；低分早停，高分继续 | 不训练第二个 failure head；不把 10 次 trial 的 10pp 当显著；不把合成榜单当校准集 |

## 1. 本轮新核实的事实（只列会改变方案的）

### 1.1 榜单仍是合成预览，不能用来训练“成功率模型”

- 2026-10-31 复核：`leaderboard.html`、`runs.html` 仍显示 **Coming Soon**；`leaderboard_data.json` 直接 `curl` 仍返回 HTML 挑战页（Cloudflare/前端兜底），只有 webfetch 能拿到 JSON。
- JSON 的 `generated_from` 是 `gen_leaderboard.py`；8 个模型的 32 维任务成功率与步骤分仍是线性生成；详情页视频是“测试视频占位”。
- 结论：**不能从榜单学失败分布，也不能把 29.7% 当 baseline。** 成功率证书的校准必须来自单任务不计分通道 + 仿真扰动 + 真实失败日志。

### 1.2 规则：单模型、32 任务 ×10 次、5 类泛化各 2 次、180 秒、N 端口

官方手册（2026-10-31 复核，中文/英文一致）明确：

- 所有任务须基于**同一模型**；模型类型不限；不得混合多个模型。
- 32 个任务，每任务 10 次独立运行；5 类泛化各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
- 单次真机执行上限 **180 秒**；排名先平均成功率，再平均步骤分，再更早提交。
- 评测跨 N 台机器人；提交从 **8765** 起暴露 N 个连续端口；每端口独立 `reset()`。
- 另有**不计分的单任务测试通道**，可用于单任务成功率/步骤分验证。

**对 UNDERWRITER 的约束**：abort/retry 必须发生在同一次 180 秒内，不能假设 evaluator 会给你重置场景；承保策略不能“跳过难任务”，只能在每个 trial 内选择技能变体和止损点。

### 1.3 API：四路 RGB、无深度/力/触觉，chunk 内没有新观测

提交模板（2026-10-31 复核）：

- 四路 RGB 480×640：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`。
- 本体：双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、`lower_body [15]`、语言 `str`。
- 动作：`control_space` 仅 `"joint"` 或 `"ee"`，互斥；`ee` 模式是绝对目标位姿 + `pivot [7]`。
- `action_chunk_size` 固定；index 0 先执行，其余顺序执行，直到 evaluator 再次 `get_action`；chunk 内没有新观测，也没有打断机制。
- **没有 depth、camera_info、force/torque、tactile**；评测端记录延迟/波动/动作统计。

**关键推论**：UNDERWRITER 的“执行中证书”只能在每个 chunk 边界更新；如果 chunk=5 @30Hz，更新周期约 167ms；如果 chunk=30，更新周期 1s，止损太晚。所以它必须继承 CHUNK-SERVO 的 5 步执行块，而不是另起一套。

### 1.5 官方基座：WLA 6B 已把“大模型”做完，缺的是“选择/止损”

- UnifoLM-WLA-1.0：6B，约 2,500h 真机数据，64 任务；默认 `chunk_size=30`、`target_fps=30`、4 步去噪；冻结 VLM，只训 DiT action head + robot-state projector，单张 24GB GPU 可微调。
- 54 维 action / 60 维 state；挑战赛 API 是 2×6 EE + 2×1 gripper + 7 pivot = 21 维；adapter 需要把相对 EE 动作 compose 到绝对位姿。
- 33k 演示不只是 imitation 数据，也是**技能卡的目标位姿/腕部目标图/时长分布/成功先验**。
- 官方仿真（IsaacLab/MuJoCo）足够做“承保策略”的压力测试，但不足以预测真机绝对成功率。

**战略结论**：不要再从零训 6B/14B；把边际算力投到“选哪个技能、什么时候停、什么时候回溯”。这是本轮与第 12 轮的分工：R12 解决“怎么执行”，R13 解决“值不值得继续执行”。

### 1.6 文献：失败预测和测试时算力都在升温，但“无训练承保 + 开放词汇技能卡”仍是空位

- **Backtrack**（arXiv:2610.32941）：冻结 VLA + 小失败预测头 + 回溯；证明了“在执行中预测失败并回退”有效。差异：它需要 outcome-labeled rollouts 训练失败头；我们优先做**无训练证书**，且把失败预测接到技能选择/止损，而不是单一策略的回溯。
- **Do VLAs Know They Will Fail?**（arXiv:2610.32208）：OpenVLA 激活的 SAE 特征包含结果预测信息，可在不可恢复前预测失败。差异：它做可解释性/探针；我们用同一 checkpoint 的多次采样一致性 + 演示支持度做工程化证书，不训练 SAE。
- **Harness VLA**（arXiv:2607.08448）：用记忆引导的 agent 把冻结 VLA 变成可靠原语。差异：它引入 LLM/agent 层；我们用结构化技能卡 + 确定性承保，避免第二个模型。
- **ELASTIC**（arXiv:2606.31132）、**DASIP**（arXiv:2511.20906）、**DIRECT**（arXiv:2606.12402）：分别做测试时算力的串行/并行分配、难度感知积分步长、具身规划器的算力路由。差异：它们优化单个策略的推理预算；我们优化**跨技能变体的选择 + 180 秒内的止损/回溯**，目标函数是“每次尝试的成功数/算力”。
- **OneTwoVLA**（arXiv:2505.11917）：单模型自适应切换“行动/推理”。差异：我们不训练双模式，只在推理时用证书决定继续/回溯。
- **VLA^2**（arXiv:2510.14902）：用外部检索/检测处理未见概念。差异：我们不引入外部大模块；技能卡是离线数据库，目标是 appearance-invariant 的 affordance。
- **Clutter-Robust VLA**（arXiv:2512.22519）、**DynamicVLA**（arXiv:2601.22153）：物体中心/几何接地、延迟感知。差异：它们改模型；我们改执行决策层，可与它们叠加。

以上事实的完整链接与检索日期见产物区 §11；核心来源是挑战赛官网/榜单 JSON、提交 README、HF 数据集元数据、WLA 仓库、飞书手册。榜单“合成”判断是我们在公开 JSON 上做的回归/相关性分析（B 级），不是官方声明。

## 2. 诊断：为什么“成功率”需要一个承保层

### 2.1 三个被混在一起的问题

一次 trial 的失败可以拆成三个不同问题：

1. **能力问题**：这个技能根本不会（OOD、物体外观/位置没见过）。
2. **执行问题**：技能会，但执行偏了（最后 3 厘米、接触、延迟）。
3. **决策问题**：技能和执行都还行，但已经进入不可恢复状态，却还在继续；或者明明还有时间重试，却把 180 秒耗在一条死路上。

第 10–12 轮主要解决 1 和 2；UNDERWRITER 解决 3。**决策问题的边际收益被低估了**：在成功率只有 20–30% 的区间，提前识别一条 doomed rollout 并切换到另一条技能变体，可能比把 VLA 再放大一档更便宜。

### 2.2 一个 trial 的“经济账”

设：

- `y ∈ {0,1}`：trial 是否成功；
- `c`：这次 trial 消耗的算力/时间（VLA 调用、采样数、伺服、重试）；
- `T=180s`：单次 trial 上限；
- `p`：成功概率；
- `r`：失败后重试成功的概率；
- `t_retry`：一次重试的最小时间。

“无条件执行”的期望成功是 `p`。允许一次止损/重试的期望成功近似：

```math
p' \approx p + (1-p)\,q\,r,
```

其中 `q` 是在不可恢复前成功止损的概率。若 `q=0.5, r=0.3`，则 `p'` 比 `p` 高 `0.15(1-p)`；在 `p=0.25` 时约 **+11.3pp 的条件增益**（不是全局承诺）。但前提是：止损不能误杀好 trial，重试不能把时间耗光，重试不能在场景已被破坏后进行。

### 2.3 为什么现在不做“更大的 VLA”

- 官方 WLA 已经 6B、2,500h、64 任务；再训一档的边际成本高，且榜单头部也只差 9pp。
- 32 任务 ×10 次只有 320 trials；全局标准误约 2.4pp，**+1–2pp 的实验噪声很大**。把工程投到“止损/重试/技能选择”这种每条 trial 都能生效的决策层，比追求模型架构的 +1pp 更划算。
- 单模型规则限制“再加一个策略”，但**技能卡是数据库，证书是打分函数，承保是控制逻辑**，都不是第二个学习策略。

## 3. 方法：UNDERWRITER 的五层

```text
┌──────────────────────────────────────────────────────────────┐
│ 1. 技能卡库（离线，33k 演示）                                │
│    verb + target affordance + receptacle affordance          │
│    language templates / relative pose / wrist goal / cost    │
└──────────────────────────────┬───────────────────────────────┘
                               │ 检索/过滤
┌──────────────────────────────▼───────────────────────────────┐
│ 2. 开放词汇解析器（在线，确定性）                            │
│    instruction -> skill family -> top-k cards -> goal        │
└──────────────────────────────┬───────────────────────────────┘
                               │ 候选技能变体
┌──────────────────────────────▼───────────────────────────────┐
│ 3. 成功率证书（无训练）                                      │
│    plan agreement / demo support / geometry / kinematics     │
│    -> score -> empirical bin -> p_lower                      │
└──────────────────────────────┬───────────────────────────────┘
                               │ 承保决策
┌──────────────────────────────▼───────────────────────────────┐
│ 4. 承保策略（选择/继续/止损/回溯）                           │
│    max p_lower s.t. time/compute; abort before commitment    │
└──────────────────────────────┬───────────────────────────────┘
                               │ 5 步动作块
┌──────────────────────────────▼───────────────────────────────┐
│ 5. 执行层（R12 CHUNK-SERVO）                                 │
│    WLA 30 步规划 + 5 步视觉伺服 + 相对目标                   │
└──────────────────────────────────────────────────────────────┘
```

- **唯一学习模型**：VLA（官方 WLA 或同架构基座）。
- **技能卡**：离线数据库，无学习权重。
- **证书**：固定公式 + 分位数校准，无梯度训练。
- **承保**：规则/动态规划，无学习权重。
- **执行**：R12 的确定性视觉伺服。

### 3.1 技能卡：把 32 个 task ID 压成 10–14 个技能族

技能卡不是“每个任务一张卡”，而是**动词 + 目标 affordance + 受器 affordance** 的组合：

| 技能族 | 例子任务 | 关键 affordance | 可复用性 |
|---|---|---|---|
| `pick_place` | 水果收集、装娃娃、摆相框 | 抓取面、放置面 | 高 |
| `insert` | 插网线、插充电器、试管、针管 | 孔/槽/轴、插入深度 | 高 |
| `hang` | 挂杯子、收纳球拍、装耳机 | 钩/挂杆/边缘 | 中 |
| `stack` | 叠碗、纸杯堆叠、餐盘 | 边缘/内壁/重心 | 高 |
| `pour` | 倒药、针管转移液体 | 瓶口/液面/倾角 | 中 |
| `zip_unzip` | 拉拉链、收拾书包 | 拉链头/轨道 | 低 |
| `unlock_open` | 开锁、开药瓶、开盒 | 锁孔/瓶盖/铰链 | 中 |
| `fold` | 叠毛巾 | 角/边/折叠线 | 低 |
| `sort_arrange` | 水果分类、颜色排列、整理工具 | 类别区域/排列槽 | 高 |
| `pack_store` | 工具箱、书包、手机、文具袋 | 容器开口/内部空间 | 高 |
| `remove` | 移除便签、挑电池 | 夹持边/吸附面 | 中 |
| `dynamic` | 传送带分拣 | 运动目标/预测拦截 | 低 |
| `assemble` | 拼字母 | 字符槽/相对位姿 | 低 |

这张表是**先验**，不是官方分类；它用于判断“新任务能不能复用旧卡”，而不是声称 32 任务只有 13 种技能。开放词汇的“开放”体现在：**新说法、同类新外观、相似 affordance 可以映射到已有卡**；没有卡就回退 VLA，并把失败写进账本。

- `success_stats` 初始为空；单任务通道每跑一次就更新，**不训练模型，只更新计数**。
- `targets` 可以有多条，来自不同演示；在线按当前受器位姿/腕部图重打分。
- `language_templates` 来自数据集语言改写 + 人工 slot 化；不依赖运行时 LLM。
- `roles` 只描述 affordance，不描述颜色/品牌；这是对“同类新外观”的泛化接口。

### 3.3 开放词汇解析：先动词/角色，再外观

在线解析不训练新模型，分三步：

1. **文本召回**：把 instruction 与技能卡的 `language_templates` 做相似度。优先用 VLA 同一 checkpoint 的文本编码器；如果服务不暴露，就用确定性 token/词形匹配 + 任务脚本先验。**不加载第二个文本模型。**
2. **角色过滤**：从 instruction 抽 target/receptacle 名词（规则/词表/最近邻），过滤掉角色不兼容的卡。例如“把杯子挂到杯架上”不能召回 `insert@peg_hole`。
3. **几何重排**：用当前图像中 target/receptacle 的可见性、相对位姿先验、演示支持度重排 top-k。**外观只用于消歧，不用于硬匹配**；颜色/材质变化不应改变技能族。

返回：

```text
候选技能变体 = [
  {card, goal, servo_mode, approach_pose, estimated_time, p_prior},
  ...
]
```

如果没有卡命中，或 top-1/top-2 margin 低于阈值：

```text
fallback_to_vla_open_loop()
log_unmatched_instruction()
```

**不硬做**：错误的技能卡比没有卡更危险。

### 3.4 成功率证书：无训练，但有校准

证书分两层：**预执行证书**（选技能前）和**执行中证书**（每个 5 步块后）。

#### 预执行特征

| 特征 | 直觉 | 计算 |
|---|---|---|
| `r_skill` | 指令与技能卡是否匹配 | top-1 与 top-2 的文本相似度 margin |
| `r_support` | 当前初始状态在成功演示里有没有支持 | 技能/位姿特征空间的 kNN 距离 |
| `r_plan` | VLA 对同一指令是否稳定 | K 次采样/语言改写的动作块两两距离 |
| `r_geom` | 目标/受器是否看得见、深度是否可信 | ROI 可见性、双目视差有效像素、位姿协方差 |
| `r_kin` | 计划是否运动学可行 | IK 残差、关节限位、碰撞 margin |
| `r_hist` | 这个技能/轴历史上成不成 | 技能卡 success_stats 的 Wilson 下界 |

#### 执行中特征

| 特征 | 直觉 | 计算 |
|---|---|---|
| `r_progress` | 是否在向目标推进 | 当前腕部图/头部 ROI 与演示目标图的相似度；阶段 FSM 进度 |
| `r_servo` | 伺服误差是否在收敛 | `||e_t||` 的斜率、接触事件、夹爪滞止 |
| `r_replan` | 重规划是否还一致 | 新 plan 与旧 plan 的动作距离 |
| `r_time` | 是否还来得及 | 已用时间 / 演示时长分位数 |
| `r_edit` | 场景是否被人改动 | R11 的 `edit_score` |

#### 打分与校准

固定权重把特征转成风险分：

```math
z_t = \sum_i w_i\,\mathrm{rank}_i(f_{t,i}),
\qquad
\hat p_t = \mathrm{WilsonLower}\big(\text{bin}(z_t)\big).
```

- 权重 `w_i` 由离线消融固定，**不做梯度训练**；换机器人只重标定分箱，不重训。
- `bin(z)` 用单任务通道的失败日志做经验分箱；样本不足时用保守分位数，并明确标注“未校准”。
- `p_lower` 是保守下界；承保用它，不用 `p_hat` 的均值。
- 证书不是概率保证；它是**排序 + 止损工具**。在 G2 过门之前，不对外声称“校准成功概率”。

#### 计划一致性怎么算

对 K 个动作块 `A^(1)...A^(K)`（每个 `H×D`，EE 空间）：

```math
d_{ij} = \mathrm{DTW}(A^{(i)}, A^{(j)}),
\qquad
r_{plan} = -\frac{2}{K(K-1)}\sum_{i<j} d_{ij}.
```

- K=3–5；采样来自同一 VLA 的不同噪声种子/语言改写/图像 crop/resize。
- 只比较前 `H_c` 步（执行块），不比较 30 步全计划；否则长尾差异会淹没即时一致性。
- 如果 K 次采样中有 1 次明显不同，`r_plan` 下降；这可能是多峰，也可能是 OOD。证书只降权，不直接判死。

### 3.5 承保策略：选择、继续、止损、回溯

#### 候选变体

每个 trial 开始时，从技能卡生成 2–4 个变体：

| 变体 | 做法 | 适用 |
|---|---|---|
| `V0 direct` | WLA 30 步开环，无伺服 | 几何不可信、变形/长程任务 |
| `V1 servo` | R12：30 步规划 + 5 步伺服 | 刚体接触、A 档任务 |
| `V2 slow` | 伺服 + 降速/增增益 | 高精度插入、透明/反光 |
| `V3 regrasp` | 换一个演示抓取位姿/接近轴 | 抓取失败、遮挡 |
| `V4 replan` | 用语言改写/新图像重规划 | 语义歧义、人为干扰 |

#### 选择规则

```text
for each variant i:
    estimate p_lower_i, cost_i, time_i
choose i* = argmax p_lower_i
    s.t. time_i + retry_reserve <= T_remaining
if no feasible:
    choose argmax p_hat_i  # 不跳过任务
```

- **不跳过任务**：即使所有变体都很低，也选最高的；竞赛要求 32 任务都做。
- `retry_reserve` 只在“承诺点之前”保留；过了承诺点，不预留重试时间，避免拖到 timeout。
- 如果 `V1` 的证书低是因为几何不可信（`r_geom` 低），选 `V0` 而不是硬做伺服；这是“承保”而不是“永远加码”。

#### 止损/回溯

```text
after each 5-step chunk:
    update z_t, p_lower_t, phase
    if p_lower_t < theta_abort
       and phase before commitment
       and T_remaining > t_retry + safety:
        retract to safe pose
        log claim
        choose next variant
        execute
    elif phase after commitment and p_lower_t < theta_recover:
        enter recovery (R11/R12): hold, relocalize, regrasp
    else:
        continue
```

- **承诺点**：第一次闭合夹爪/第一次插入超过 `d_commit`/第一次释放物体/液体离开容器。承诺前止损便宜；承诺后只做恢复，不假装能“重开”。
- `theta_abort` 用校准集选，目标不是最大化 abort 数，而是最大化 `p'`；误杀好 trial 的代价要计入。
- 最多 1 次重试（`R=1`），除非任务时长分布显示还有充足余量；重试也要走同一承保规则，不能无限套娃。
- 任何异常返回安全 hold/retract，绝不返回 NaN 或错误形状。

### 3.6 商业模式：把“按成功率收费”变成算法约束

这不是商业计划书，而是一个有用的目标函数。把竞赛映射成服务：

| 商业概念 | 竞赛映射 | 算法实现 |
|---|---|---|
| 产品 | 一次成功 trial | `y ∈ {0,1}` |
| 价格 | 分数/排名 | 平均成功率、步骤分、提交时间 |
| 成本 | GPU 秒 + 180s + 端口占用 | `c` |
| 核保 | 执行前成功率下界 | `p_lower` |
| 止损 | 早停 | `theta_abort` |
| 理赔 | 失败日志 | `claim` |
| 再保险 | 单任务不计分通道 | 校准/回放 |
| 复利 | 失败日志更新技能卡统计 | 不重训模型 |

目标不是“每个 trial 都成功”，而是：

```math
\max \;\; \mathbb{E}[y]
\quad \text{s.t.} \quad
\mathbb{E}[c] \le C,\;\; t \le 180s.
```

如果算力紧（N 端口共享 GPU），用拉格朗日乘子：

```math
\max_i \;\; p_i - \lambda c_i,
```

`λ` 是“每 GPU 秒的机会成本”。这比“所有 trial 都采样 5 次”更合理：简单 trial 用 K=1，困难 trial 用 K=3–5。

**单位经济学**：

```math
\text{success per GPU-hour} =
\frac{p}{c_{\mathrm{vla}} + p\,c_{\mathrm{exec}} + (1-p)\,c_{\mathrm{retry}}}.
```

这个指标决定：值不值得为一个技能卡做 5 次采样？值不值得为一个人为干扰轴做恢复？值不值得为一个低成功率任务写卡？答案不是“越多越好”，而是“边际成功/边际算力”。

### 3.7 数据飞轮：失败日志比成功演示更稀缺

33k 演示全是成功，缺少失败分布。数据飞轮：

```text
单任务通道 baseline/servo A/B
    -> 记录 success/failure + 证书特征 + 阶段 + 轴
    -> 更新技能卡 success_stats / 分箱阈值
    -> 下一轮选更聪明的变体
    -> 只把高价值失败写入长期账本
```

- 不训练模型；只更新计数、分位数、技能卡统计。
- 失败日志按 `task, skill_family, axis, phase, variant` 分片；避免把位置泛化的失败错误归因到技能。
- 人为干扰/未见物品的失败单独记账；这两轴是 40% 的 trial，不能混在“普通失败”里。
- 如果评测端不返回成功标签，用自监督代理（目标图进度、接触事件、阶段完成）记“疑似失败”；只在单任务通道用真实标签校准。

## 4. 与第 10–12 轮的关系：不是替换，是加“决策层”

| 轮次 | 层 | R13 怎么接 |
|---|---|---|
| R10 FACT-VLA | 相位化 BC、CAC 柔顺、EGP 证据门控 | 技能卡的 phase/动作先验复用；不重训 |
| R11 GEO-RESIDUAL | 动作条件化残差、米制距离、编辑检测 | 证书的 `r_edit`/`r_geom` 复用；恢复复用 |
| R12 CHUNK-SERVO | 30 步规划 + 5 步伺服 + 相对目标 | 作为 `V1` 执行层；证书决定 servo on/off |
| **R13 UNDERWRITER** | **技能选择/成功率证书/止损/回溯** | **在 R12 之上加决策层** |

组合后的 `get_action`：

```text
obs -> 开放词汇解析 -> 候选技能变体
    -> 预执行证书 -> 承保选择
    -> WLA 30 步规划 -> R12 5 步伺服
    -> 执行中证书 -> 继续/止损/恢复
    -> 5 步动作 + token
```

**保留**：官方 WLA、33k 演示、R12 的 5 步伺服、R11 的编辑检测、R10 的相位。
**剪枝**：从零训 VLA/World Model、完整 sim-to-real 策略训练、第二个学习策略、6D 物体位姿网络、力/触觉闭环（API 没有）、把合成榜单当校准集。
**新增**：技能卡、开放词汇解析、成功率证书、承保策略、失败账本。

## 5. 创新点清单（含动机/差异/可行性/资源/步骤/风险）

> 评分：★ 主押注；☆ 集成；○ 消融。收益是相对“R12 无条件执行”的**全局成功率**粗估，不是保证。

### I1 ★ OV-SKILL CARD：把 33k 演示压成 10–14 个开放词汇技能族

- **动机**：32 个 task ID 不能覆盖新说法/同类新外观；但底层 affordance 可以复用。技能卡让“新任务上线”从重训模型变成写一张卡。
- **差异**：不是按任务建 32 个策略，也不是外部 VLM 检测器；是 `verb + target affordance + receptacle affordance` 的结构化数据库，目标位姿/腕部图来自成功演示。
- **可行性**：33k 演示已有；相位分割用 R10/R11；相对位姿/腕部图用 R12 管线；不需要新标注（先验卡 + 自动统计）。
- **资源**：1–2 人日 schema + 32 任务映射；CPU 离线；存储 <1GB（关键帧/描述子）。
- **步骤**：schema → 任务映射 → 自动抽目标位姿/腕部图 → 人工审 32 任务 → 留出语言改写评测。
- **风险**：技能族划分错误会把错误卡召回；用角色过滤 + top-k 重排 + 低置信回退 VLA；先只在高复用族（insert/hang/stack/pick_place）启用。
- **收益**：不是直接涨点，而是让 I2/I3 有可选择的“技能变体”；间接 +1–3pp；证据 B/C。

### I2 ★ SUCCESS-CERT：无训练的成功率证书

- **动机**：VLA 不知道自己什么时候会失败；Backtrack 证明失败可预测，但需要失败头和 outcome labels。竞赛没有 32 任务的失败标签，单模型规则也不欢迎第二个学习策略。
- **差异**：用同一 checkpoint 的多次采样一致性 + 演示支持度 + 几何/运动学可行性 + 历史统计，做**固定公式 + 分位数校准**；不训练 failure head/SAE/第二个编码器。
- **可行性**：K 次采样只是同一模型多次推理；特征都可在 API 观测/演示索引里算；CPU 开销小。
- **资源**：1 人 2 周；单任务通道收集 ≥30 个失败样本用于分箱；GPU 推理 K=3–5。
- **步骤**：特征实现 → 离线回放/扰动集 → 分箱/置信下界 → 单任务校准 → 门 G1/G2。
- **风险**：计划一致性可能惩罚多峰正确解；用“低分只降权/止损，不直接判死”；校准集分布偏移时退回保守分位数。
- **收益**：止损/重试的上游；单独不涨点，和 I3 一起 +3–6pp；证据 B/C。

### I3 ★ UNDERWRITE：选择/继续/止损/回溯的承保策略

- **动机**：180 秒内，继续一条 doomed rollout 会浪费唯一的重试窗口；无条件执行是当前所有 VLA 的共同浪费。
- **差异**：不是“失败后回溯”单点，而是**执行前选变体 + 执行中止损 + 承诺点后恢复**的三段式；目标函数是成功/算力，不是最大 chunk 数。
- **可行性**：R12 已有 5 步块和状态机；承诺点用夹爪/接触事件；重试用 retract + 下一变体，不需要 evaluator reset。
- **资源**：1 人 3 周；仿真扰动 + 单任务 A/B；无额外训练。
- **步骤**：变体定义 → 证书接入 → 承诺点检测 → 止损/重试 → 单任务 A/B → 全量干跑。
- **风险**：误杀好 trial、重试破坏场景、timeout；用保守 `theta_abort`、承诺点前才重试、最多 1 次、预留安全时间。
- **收益**：条件增益 +3–8pp；全局 +2–5pp；证据 B/C。

### I4 ☆ LOSS-LEDGER：失败账本与技能卡再校准

- **动机**：33k 演示全是成功，失败样本才是稀缺资产；没有失败账本，证书永远无法校准。
- **差异**：不是训练数据飞轮，而是**计数/分位数/技能卡统计**的轻量账本；单任务通道是“再保险”。
- **可行性**：每次 trial 记录特征/阶段/轴/结果；更新 JSON/Parquet；CPU。
- **资源**：0.5 人周；存储小；需要评测端标签或代理。
- **步骤**：日志 schema → 单任务通道接入 → 分箱更新 → 版本化。
- **风险**：标签噪声/分布偏移；按任务/轴分片，设最小样本数；不把代理当真实标签。
- **收益**：让 I2/I3 从“拍脑袋”变成“可校准”；间接 +1–3pp；证据 B。

### I5 ☆ PARAPHRASE ENSEMBLE：用官方语言改写做免费鲁棒性

- **动机**：HangCup 的 `tasks.parquet` 至少有 5 条语言改写；这是现成的开放词汇监督，不用白不用。
- **差异**：不是运行时 LLM 生成，而是离线读取官方改写 + 模板 slot；用改写间计划一致性做证书特征。
- **可行性**：逐任务读取 `tasks.parquet`；没有改写的任务用模板生成/人工写 2–3 条。
- **资源**：0.5 人周；CPU；无训练。
- **步骤**：读取所有任务改写 → 去重/槽位化 → 计划一致性评测 → 接入 I2。
- **风险**：不是所有任务都有多条；模板生成可能不自然；只用官方改写优先，模板仅消融。
- **收益**：+0.5–2pp；证据 B/C。

### I6 ○ PORTFOLIO：把工程预算当投资组合

- **动机**：32 任务不能平均用力；成功率证书/失败账本可以告诉你哪类任务的边际收益最高。
- **差异**：不是按榜单排名选任务（榜单是合成的），而是按 `q_t×Δ_t/cost_t` 和单任务通道的实测失败阶段选。
- **可行性**：R12 已有 A/B/C 分档；失败账本提供 `q_t`；单任务通道提供 `Δ_t`。
- **资源**：0.5 人周；评测时间。
- **步骤**：先验分档 → 5 任务 A/B → 更新优先级 → 每 3–5 任务重排。
- **风险**：过拟合小样本；用配对设计 + 置信区间；不因一次失败砍掉整个任务。
- **收益**：不直接涨点，但提高工程 ROI；证据 B。

## 6. 实验门 G0–G7

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | 技能卡能否覆盖 32 任务？ | 32/32 有卡或明确 fallback；top-5 语言改写召回 ≥90% | 只在高复用族启用；其余回退 VLA |
| G1 | 证书能否排序失败？ | 留出扰动集 AUROC ≥0.75；误杀好 trial ≤14% | 只用 `r_geom/r_kin` 硬门；不做概率声明 |
| G2 | 证书是否校准？ | 至少 30 个失败样本；ECE ≤0.10；保守覆盖率 ≥90% | 退回分位数阈值；只做相对排序 |
| G3 | 承保是否净涨点？ | 5 任务中 ≥3 个 +5pp；timeout 不升；FoldTowel 不回归 | 关闭止损，只保留技能选择 |
| G4 | 重试是否值得？ | 重试成功率 ≥30%；净成功 ≥ 不重试；平均时长 ≤150s | 最多 1 次；只在承诺点前 |
| G5 | 开放词汇是否有效？ | 同类新外观 top-5 召回 ≥80%；不改任务脚本 | 只做语言改写；外观回退 VLA |
| G6 | 系统是否稳定？ | N 端口隔离；reset 干净；内存不涨；p99 ≤150ms | 回退 R12 基线 |
| G7 | 消融是否支持因果？ | 证书 > 随机；承保 > 无条件；卡 > task ID；K=3 > K=1 | 砍掉无效部分，不硬保留 |

统计注意：

- 每任务 10 次，10pp = 1 次 trial；单任务 A/B 只能用方向性判断，不能声称显著。
- 5 任务 ×10 次 A/B 的配对差值用 bootstrap 95% CI；CI 跨 0 不提交。
- 320 trials 的全局 SE 约 2.4pp；不要用 +1–2pp 做结论。
- 人为干扰轴 = 20%；若 human 轴 +10pp，全局约 +2pp；这是算术，不是实验结果。

## 7. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定为第二个模型 | VLA 是唯一策略；技能卡是数据库；证书是固定打分；承保是规则；可选 C3 用同一 checkpoint 特征并说明 |
| 证书误杀 | 好 trial 被 abort | 保守阈值；承诺点前才止损；误杀率纳入目标；低置信不 abort |
| 重试破坏场景 | 第二次更差 | 只在承诺点前 retract；承诺后只做恢复；最多 1 次 |
| 失败样本不足 | 证书无法校准 | 单任务通道 + 仿真扰动；样本 <30 只做排序，不声称概率 |
| 技能卡召回错 | 用错目标位姿 | 角色过滤 + top-k 重排 + margin 门；低置信回退 VLA |
| 开放词汇过度承诺 | 新类别失败 | 明确只覆盖“同类新外观/新说法”；无卡回退并记账 |
| 计划一致性惩罚多峰 | 正确但多样的计划被低分 | 只降权不判死；用 top-k 变体保留多样性 |
| 180s timeout | 重试耗尽时间 | 预留 `t_retry + safety`；平均时长监控；p99 门 |
| 端口串扰 | N 端口互相污染 | 每端口独立状态/账本；共享只读技能卡/模型权重 |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |
| 榜单误导 | 用合成分数校准 | 榜单只作预览；证书校准只用单任务通道/仿真 |
| 计算开销 | K 次采样拖慢 | 简单 trial K=1；困难 trial K=3–5；异步采样；按 `p-λc` 分配 |

**合规三种模式**：

- **C1 离线标注**：技能卡/证书只离线生成，线上只用 VLA + 规则；最保守。
- **C2 确定性控制器**（主推）：技能卡数据库 + 固定公式证书 + 规则承保；无学习权重。
- **C3 同 checkpoint 特征**：文本/图像描述子用 VLA 同一 checkpoint 的 encoder；不加载第二个模型；需向官方说明。

禁止：加载第二个学习策略/失败预测网络/独立视觉编码器做在线决策；用外部 LLM 在运行时生成技能/计划；用合成榜单训练任何东西。

## 8. 一句话押注

**把 33k 成功演示压成开放词汇技能卡，用同一 VLA 的多次采样一致性和演示支持度开一张无训练的成功率证书，再用“承保策略”在 180 秒内选择技能、止损、回溯——不卖更大的模型，卖可兑现的成功率。**

## 2. 问题形式化

### 2.1 评分与不确定性

总分：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

320 trials 下，若 `p≈0.25`，单次标准误：

```math
\mathrm{SE}(S)\approx \sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

每任务 10 次，10pp = 1 次 trial；单任务 A/B 只能看方向，不能看显著。报告必须给配对差值的 bootstrap 95% CI，而不是只报两个平均值。

人为干扰轴：

```math
\Delta S_{\mathrm{human}} = \frac{2}{10}\,\Delta p_h = 0.2\,\Delta p_h.
```

即 human 轴 +10pp → 全局 +2pp。

### 2.2 承保目标

设一次 trial 选择变体 `i`，成功概率 `p_i`，成本 `c_i`（GPU 秒/端口占用/执行时间），失败后可止损并以概率 `q` 在承诺点前重试，重试成功概率 `r`，重试成本 `c_r`。期望成功与期望成本：

```math
p_i' = p_i + (1-p_i)\,q_i\,r_i,
\qquad
c_i' = c_i + (1-p_i)\,q_i\,c_{r,i}.
```

承保选择：

```math
i^* = \arg\max_i \;\; p_i' - \lambda c_i',
\quad \text{s.t.}\quad t_i' \le 180s,
```

其中 `λ` 是每 GPU 秒的机会成本。若没有可行变体，退化为 `argmax p_i`，**不跳过任务**。

### 2.3 反馈周期

设 `f_c` 为控制频率，`H_c` 为 chunk，`τ` 为 RTT + 推理 + 图像传输，反馈周期：

```math
T_{\mathrm{fb}} \approx \frac{H_c}{f_c} + \tau.
```

| 场景 | `H_c` | `f_c` | `τ` | `T_fb` | 评价 |
|---|---:|---:|---:|---:|---|
| 官方 WLA 默认 | 30 | 30 | 50ms | **1050ms** | 止损太晚 |
| R12 保守 | 5 | 30 | 50ms | **217ms** | 可用 |
| R12 高延迟 | 5 | 30 | 150ms | **317ms** | 降增益/只 PBVS |
| 低控制频率 | 5 | 10 | 50ms | **550ms** | 改 `H_c=3` |
| 极低延迟 | 3 | 30 | 20ms | **120ms** | 动态任务可用 |

**结论**：UNDERWRITER 的执行中证书必须挂在 `H_c=5`（或 3/8）的块边界；`H_c=30` 只能做预执行选择，不能做止损。

### 2.4 证书的统计定义

给定风险分 `z`，用校准集分箱：

```math
\hat p(b) = \frac{1}{n_b}\sum_{j\in b} y_j,
\qquad
p_{\mathrm{lower}}(b) = \mathrm{WilsonLower}(\hat p(b), n_b, \alpha).
```

Wilson 下界（单侧）：

```math
p_{\mathrm{lower}} =
\frac{\hat p + \frac{z_\alpha^2}{2n} - z_\alpha\sqrt{\frac{\hat p(1-\hat p)}{n}+\frac{z_\alpha^2}{4n^2}}}
{1+\frac{z_\alpha^2}{n}}.
```

- `n_b` 小于最小样本数（如 20）时，不声称校准；用全局分位数或保守先验。
- 证书只保证“在同一校准分布下的经验下界”，不是对任意新任务的概率保证。
- 报告 ECE、Brier、AUROC、覆盖率；不只报准确率。

### 2.5 计划一致性

对 K 个动作块 `A^(1)...A^(K)`（每个 `H×D`，EE 空间）：

```math
d_{ij} = \mathrm{DTW}(A^{(i)}, A^{(j)}),
\qquad
r_{\mathrm{plan}} = -\frac{2}{K(K-1)}\sum_{i<j} d_{ij}.
```

- K=3–5；采样来自同一 VLA 的不同噪声种子/语言改写/图像 crop/resize。
- 只比较前 `H_c` 步（执行块），不比较 30 步全计划。
- 归一化：除以演示中同类动作块的平均 DTW，避免任务尺度差异。
- 计划一致性低不直接判死；它只是证书的一个特征。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port UnderwriterPolicy (CPU)   │
                    │  ├─ OV resolver                     │
                    │  ├─ success certificate             │
                    │  ├─ underwriting policy             │
                    │  ├─ CHUNK-SERVO executor            │
                    │  └─ loss ledger (local)             │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared VLA server (GPU)            │
                    │  UnifoLM-WLA-1.0 / VLA-0            │
                    └─────────────────────────────────────┘
```

- 每个端口一个 `UnderwriterPolicy` 实例，独立 `reset()`、技能状态、证书状态、账本。
- 技能卡/演示索引/校准表只读共享；N 端口用 copy-on-write 或 mmap。
- VLA 请求异步、可批处理；K 次采样按端口预算限流。
- 共享 VLA server 用 session ID 区分端口；模型权重只有一份，不违反单模型。

#### 3.2.3 离线构建

```text
for each episode:
    phases = segment(episode)                  # R10 CPT / R11 事件
    for each phase:
        k = select_keyframe(phase)             # 首次接触前/目标可见/距离<5cm
        T_base_target = estimate_target(episode, k)   # stereo + 局部几何
        T_base_ee = episode.state[k].ee_pose
        T_target_ee = inv(T_base_target) @ T_base_ee
        I_wrist = episode.wrist[k]
        card = map_to_skill_family(task, phase)      # 先验 + 人工审
        index.add(card, T_target_ee, I_wrist, quality)
```

关键帧选择：

- 接触任务：首次接触前 1–3 帧 + 接触稳定后 1 帧；
- 挂/叠/插入：目标进入腕部视野且夹爪距离 <5cm；
- 拉链/锁：夹爪咬合前；
- 变形任务：不建精确相对目标，只建相位/语义目标；伺服不启用。

目标位姿估计：

- 刚体受器：头双目 + 局部 ICP/平面/圆/线拟合；
- 透明/反光：腕部目标图 + 头双目粗深度；置信度低不建库；
- 目标被夹爪挡住：用演示 EE 位姿反推，或只存腕部目标图；
- 人为干扰：目标位姿在线重估，不依赖离线绝对位姿。

### 3.3 开放词汇解析器

```text
input: instruction l, images I, state s
1. text recall:
     scores = cosine(embed(l), embed(card.language_templates))
     if no text encoder: token/word matching + task prior
2. role filter:
     (target_noun, receptacle_noun) = extract_roles(l)
     cards = [c for c in top_k if roles_compatible(c, nouns)]
3. geometry rerank:
     cards = rerank(cards, visibility(I), pose_prior(s), support(c))
4. margin gate:
     if top1 - top2 < theta_margin:
         return fallback_vla()
5. return variants(cards)
```

- 文本嵌入优先用 VLA 同一 checkpoint 的文本编码器；如果服务不暴露，用确定性 token/词形 + 任务脚本先验；**不加载第二个文本模型**。
- 角色抽取用词表/规则/最近邻；不依赖运行时 LLM。
- 外观只用于消歧（同类不同颜色/材质），不用于硬匹配；技能族由动词/affordance 决定。
- 没有卡命中 → 回退 VLA 开环 + 记录 `unmatched_instruction`；不硬做错误卡。

### 3.4 成功率证书

#### 预执行特征

| 特征 | 直觉 | 计算 | 失效回退 |
|---|---|---|---|
| `r_skill` | 指令与卡是否匹配 | top-1/top-2 文本相似度 margin | 低 → 回退 VLA |
| `r_support` | 初始状态有没有成功演示支持 | 技能/位姿特征空间 kNN 距离 | 低 → 降低先验，不直接 abort |
| `r_plan` | VLA 对同指令是否稳定 | K 次采样/改写/增广的动作 DTW | 低 → 保留 top-k 变体 |
| `r_geom` | 目标/受器可见、深度可信 | ROI 可见性、视差有效像素、位姿协方差 | 低 → 关闭伺服/IBVS |
| `r_kin` | 计划运动学可行 | IK 残差、关节限位、碰撞 margin | 低 → 重规划/换接近轴 |
| `r_hist` | 技能/轴历史成功率 | `success_stats` 的 Wilson 下界 | 样本不足 → 全局先验 |

#### 执行中特征

| 特征 | 直觉 | 计算 |
|---|---|---|
| `r_progress` | 是否向目标推进 | 当前腕部图/头部 ROI 与演示目标图相似度；阶段 FSM 进度 |
| `r_servo` | 伺服误差是否收敛 | `||e_t||` 斜率、接触事件、夹爪滞止 |
| `r_replan` | 重规划是否还一致 | 新 plan 与旧 plan 的 DTW |
| `r_time` | 是否还来得及 | 已用时间 / 演示时长分位数 |
| `r_edit` | 场景是否被人改动 | R11 `edit_score` |

#### 打分

```math
z_t = \sum_i w_i\,\mathrm{rank}_i(f_{t,i}),
\qquad
\hat p_t = \mathrm{WilsonLower}\big(\text{bin}(z_t)\big).
```

- 权重 `w_i` 由离线消融固定，不做梯度训练；换机器人只重标定分箱。
- `rank_i` 用校准集经验 CDF，避免量纲问题；没有校准集时用固定阈值归一化。
- `p_lower` 是保守下界；承保用它。
- 证书不是概率保证；G2 过门前只做排序/止损，不对外声称校准成功概率。

#### 校准协议

1. **数据**：单任务通道，5 个代表任务 ×10 次 ×2 变体（baseline/servo）；目标 ≥30 个失败样本。
2. **划分**：按任务/初始条件/轴分组，不能把相邻帧分到训练/校准。
3. **分箱**：`z` 的 5–10 个分位箱；每箱 ≥20 样本；不足则合并。
4. **指标**：ECE、Brier、AUROC、保守覆盖率（`p_lower ≤ y` 的比例）。
5. **报告**：给 95% bootstrap CI；ECE >0.10 或覆盖率 <90% 时退回分位数阈值。
6. **不泄漏**：不用正式 320 trials 调阈值；正式评测只读冻结的校准表。

### 3.5 承保策略

#### 候选变体

| 变体 | 做法 | 适用 | 成本 |
|---|---|---|---|
| `V0 direct` | WLA 30 步开环，无伺服 | 几何不可信、变形/长程 | 1× VLA |
| `V1 servo` | R12：30 步规划 + 5 步伺服 | 刚体接触、A 档 | 1× VLA + CPU |
| `V2 slow` | 伺服 + 降速/增增益 | 高精度插入、透明/反光 | 1× VLA + CPU |
| `V3 regrasp` | 换演示抓取位姿/接近轴 | 抓取失败、遮挡 | 1× VLA + 检索 |
| `V4 replan` | 语言改写/新图像重规划 | 语义歧义、人为干扰 | 1–2× VLA |

#### 选择规则

```text
variants = generate_variants(cards, obs)
for v in variants:
    v.p_lower = certificate.pre(v, obs)
    v.cost = estimate_cost(v)
    v.time = estimate_time(v)
feasible = [v for v in variants if v.time + retry_reserve <= T_remaining]
if feasible:
    v* = argmax_v (v.p_lower - lambda * v.cost)
else:
    v* = argmax_v v.p_hat          # 不跳过任务
execute(v*)
```

- `retry_reserve` 只在承诺点前保留；承诺后不预留。
- 如果 `V1` 的证书低是因为 `r_geom` 低，选 `V0`；不要硬做伺服。
- 简单 trial 用 K=1 采样；困难 trial 用 K=3–5；按 `p-λc` 分配。

#### 承诺点

```text
commitment = first of:
    gripper closed on target
    insertion depth > d_commit
    object released
    liquid left container
    zipper/lock engaged
```

- 承诺前：止损便宜；可以 retract → 换变体 → 重试（最多 1 次）。
- 承诺后：只做恢复（hold/relocalize/regrasp），不假装能“重开”；避免破坏场景。

#### 止损/回溯

```text
after each 5-step chunk:
    update z_t, p_lower_t, phase
    if p_lower_t < theta_abort
       and phase before commitment
       and T_remaining > t_retry + safety:
        retract to safe pose
        log claim
        choose next variant
        execute
    elif phase after commitment and p_lower_t < theta_recover:
        enter recovery (R11/R12): hold, relocalize, regrasp
    else:
        continue
```

- `theta_abort` 校准目标：最大化 `p'`，不是最大化 abort 数；误杀好 trial 计入损失。
- 最多 1 次重试；除非任务时长分布显示充足余量，且第二次也在承诺前。
- 异常 → 安全 hold/retract；绝不返回 NaN/错误形状。

### 3.6 执行层：复用 R12 CHUNK-SERVO

```text
VLA:   每 30 步产出一个 30 步 plan；后台线程；不阻塞 get_action
Servo: 每 5 步用最新腕部/头部图修正一次；返回 5 步 chunk
API:   metadata.action_chunk_size = 5
```

动作：

```text
a_ff = VLA plan[t : t+H_c]          # H_c = 5
e = servo_error(obs_t, goal)         # 6D：xyz + rotvec
Δ = clip(K_p e + K_d ė, ±δ_p, ±δ_r)
a_cmd = a_ff ∘ exp(Δ)
```

- `V0` 关闭伺服；`V1/V2` 开启；`V3` 换相对目标/接近轴；`V4` 重规划。
- 相对目标来自技能卡；位置/人为干扰时在线重估 `T_base_target`。
- 接触段法向缩幅/低通；`r_grasp` 突变 → 滑移 → 重抓。
- `edit_score` 超阈值 → 停 → 重定位 → 重规划。
- 如果 `||Δ||` 连续 3 块超阈值 → 目标估计/标定异常 → 回退 VLA。

### 3.7 失败账本

```json
{
  "trial_id": "…",
  "task": "HangCup",
  "skill_family": "hang",
  "axis": "position",
  "phase": "align",
  "variant": "V1_servo",
  "outcome": "fail",
  "certificate": {"z": 0.31, "p_lower": 0.18},
  "features": {"r_skill": 0.82, "r_support": 0.44, "r_plan": 0.61, "r_geom": 0.55, "r_kin": 0.91},
  "time": 41.2,

  "notes": "target moved by human"

```

- 按 `task, skill_family, axis, phase, variant` 分片；避免把位置泛化失败错误归因到技能。
- 失败日志只更新计数/分位数；不训练模型。
- 如果评测端不返回成功标签，用自监督代理（目标图进度、接触事件、阶段完成）记“疑似失败”；只在单任务通道用真实标签校准。

## 4. 开放词汇：只承诺“同类新外观/新说法”

### 4.1 官方定义

官方“未见物品”是**同类但外观明显不同**（颜色/形状/材质替换），不是全新类别。5 类泛化各 20%；外观/语义类（干扰物 + 背景 + 未见物品）合计 60%。

因此 UNDERWRITER 的开放词汇目标是：

- 新说法：同一任务的不同语言改写；
- 同类新外观：杯子换颜色/材质，但仍可挂；网线换颜色，但仍可插；
- 相似 affordance：不同物体共享 `insert/hang/stack/pack` 技能族。

**不承诺**：全新类别、全新任务、全新工具；没有卡就回退 VLA，并记录。

### 4.2 为什么用 affordance 而不是外观

- 33k 演示覆盖 32 任务，但外观长尾无限；颜色/材质匹配会把“红杯子”卡死。
- 任务成功依赖的是：可抓面、孔/槽、钩/边缘、容器开口、放置面；这些是 affordance。
- 技能卡用 `verb + target affordance + receptacle affordance` 索引；外观只做消歧。
- 目标位姿/腕部图仍来自演示，但在线按当前受器位姿重估；外观变化不影响相对几何。

### 4.3 语言改写

- 优先读取每个任务 `tasks.parquet` 的官方改写；HangCup 已核实 5 条。
- 没有多条改写的任务，用人工模板补 2–3 条；模板只用于消融，不冒充实测监督。
- 证书的 `r_plan` 可以跨改写比较：同一技能在不同说法下动作一致 → 语言 grounding 稳定。
- 运行时不用 LLM 生成改写；所有改写离线准备。

### 4.4 失败回退

```text
if no card:
    VLA open-loop
    log unmatched_instruction
if top1-top2 margin < theta:
    VLA open-loop
    log ambiguous_instruction
if card geometry invalid:
    VLA open-loop / V0
    log geometry_fallback
```

回退不是失败；它是承保的“拒保”分支。拒保也要记录，供下一轮写卡。

### 5.3 真机单任务

| 项 | 设计 |
|---|---|
| 任务 | PlugInEthernet、HangCup、ZipUp、StackBowls、FoldTowel |
| 次数 | 每任务 10 次 ×2 变体（无条件/R12 vs UNDERWRITER） |
| 初始条件 | 同一位置/背景；尽量配对 |
| 指标 | 成功率、步骤分、耗时、p99、止损次数、重试成功率 |
| 门 | ≥3/5 任务 +5pp；timeout 不升；FoldTowel 不回归 >5pp |
| 统计 | 配对差值 + bootstrap 95% CI；CI 跨 0 不提交 |

为什么选这 5 个：

- PlugInEthernet：插入，承诺点清晰，止损价值高；
- HangCup：挂，几何/相对目标；
- ZipUp：拉链，长接触、承诺点后恢复；
- StackBowls：叠，放置/释放；
- FoldTowel：变形，防回归；证书应学会“不要乱 abort”。

### 5.4 全量干跑

| 项 | 设计 |
|---|---|
| 任务 | 32×10 |
| 端口 | N 个连续端口 |
| 指标 | 总平均成功率、步骤分、p99、timeout、内存、端口串扰 |
| 门 | 无串扰；reset 干净；内存不涨；p99 ≤150ms；timeout 不升 |

### 5.5 消融

1. 证书 vs 随机选择。
2. 承保 vs 无条件执行。
3. 止损 on/off；重试 on/off。
4. 技能卡 vs task ID。
5. 官方语言改写 vs 单 prompt。
6. K=1/3/5。
7. `V1 servo` vs `V0 direct`。
8. 承诺点前/后止损。
9. 固定阈值 vs 分位数校准。
10. 失败账本更新 vs 冻结。

### 5.6 门 G0–G7

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | 技能卡能否覆盖 32 任务？ | 32/32 有卡或明确 fallback；top-5 语言改写召回 ≥90% | 只在高复用族启用；其余回退 VLA |
| G1 | 证书能否排序失败？ | 留出扰动集 AUROC ≥0.75；误杀好 trial ≤14% | 只用 `r_geom/r_kin` 硬门；不做概率声明 |
| G2 | 证书是否校准？ | ≥30 失败样本；ECE ≤0.10；保守覆盖率 ≥90% | 退回分位数阈值；只做相对排序 |
| G3 | 承保是否净涨点？ | 5 任务中 ≥3 个 +5pp；timeout 不升；FoldTowel 不回归 | 关闭止损，只保留技能选择 |
| G4 | 重试是否值得？ | 重试成功率 ≥30%；净成功 ≥ 不重试；平均时长 ≤150s | 最多 1 次；只在承诺点前 |
| G5 | 开放词汇是否有效？ | 同类新外观 top-5 召回 ≥80%；不改任务脚本 | 只做语言改写；外观回退 VLA |

| G7 | 消融是否支持因果？ | 证书 > 随机；承保 > 无条件；卡 > task ID；K=3 > K=1 | 砍掉无效部分，不硬保留 |

## 6. 竞赛策略与资源

### 6.1 失败模式分诊

| 失败模式 | 典型任务 | 该投什么 | 不该投什么 |
|---|---|---|---|
| 最后接触/插入/挂/叠/拉链/锁 | PlugInEthernet、HangCup、ZipUp、StackBowls、Unlock、ArrangeTestTubes、ToolboxStorage | R12 伺服 + 技能卡 + 证书 | 更大 VLA、更多语义数据 |
| 位置/人为干扰 | 5 类泛化轴；human_1/4 | 重定位 + 恢复 + 证书止损 | 固定轨迹、开环 chunk |
| 背景/干扰物/未见物品 | FruitSorting、ColorArrangement、OrganizeTools | 技能卡 affordance + VLA 数据增强 | 纯几何伺服 |
| 变形/语义/长程 | FoldTowel、PackBag、SpellRobot、ConveyorSorting | VLA 基座 + `V0` 直通 + 不要乱 abort | 6D 物体位姿网络 |

### 6.2 任务组合（先验）

- **A 档：伺服/承保优先（19 个）**：HangCup、DisconnectEthernet、ToolboxStorage、PlugCharger、Unlock、ArrangeTestTubes、OpenPillBottle、OrganizeStationery、PackBag、ZipUp、PaperCupStacking、StoreRacket、StackCups、PlugInEthernet、StackBowls、StoreEarphones、PackPhone、OrganizePencilCase、SyringeWaterTransfer。
- **B 档：VLA 优先（13 个）**：FruitCollection、PackDoll、FruitSorting、ColorArrangement、PlacePhotoFrame、OrganizeBookshelf、PickOutBatteries、OrganizeTools、FoldTowel、ArrangePlates、SpellRobot、ConveyorSorting、RemovePinnedNote。
- **C 档：低投入/观察**：单任务通道里 `p_t` 接近 0 且失败在早期感知/抓取的任务；保留 VLA 基线。

优先级：

```text
priority_t = q_t * Δ_t / cost_t
```

- `q_t`：失败发生在可止损阶段的比例（先验，单任务通道后更新）；
- `Δ_t`：承保条件增益（A/B 差值）；
- `cost_t`：工程/评测成本。

先做 A 档中 `q_t` 高、`cost_t` 低的 3–5 个任务；不要一次铺 19 个。

### 6.3 单位经济学

```math
\text{success per GPU-hour} =
\frac{p}{c_{\mathrm{vla}} + p\,c_{\mathrm{exec}} + (1-p)\,c_{\mathrm{retry}}}.
```

| 方案 | 成本（估算） | 预期收益 | 建议 |
|---|---|---|---|
| 官方 WLA 直接适配 | 1–2 人周 | 基线；可能 20–30% | 必做；先锁基线 |
| R12 CHUNK-SERVO | 3–4 人周 + 1 GPU 周 | A 档 +10–15pp → 全局 +3–5pp | 执行层 |
| UNDERWRITER | 3–4 人周 + 1 GPU 周 | 条件 +3–8pp → 全局 +2–5pp | 主投（叠加 R12） |
| 完整世界模型 | 8+ GPU 周 | 不确定；延迟更差 | 不做 |
| 32 任务各训策略 | 规则禁止 | — | 不做 |

收益算术：

- A 档 19 任务各 +10pp → `19/32×10=+5.9pp`；各 +5pp → +3.0pp；
- 承保在 A 档 +5pp → +3.0pp；human 轴 +10pp → +2pp；
- 保守合计 +3–6pp；乐观 +8–10pp；这些是设计目标，不是承诺。

### 6.4 提交节奏

1. **W0**：官方 WLA + API adapter + chunk 30 基线；单任务通道 1 任务，确认接口/`pivot`/token。
2. **W1**：R12 CHUNK-SERVO；5 任务 A/B。
3. **W2–W3**：技能卡 + 证书；离线/仿真。
4. **W4**：承保策略；单任务 A/B；证书校准。
5. **W5**：全量干跑；p99/内存/端口。
6. **W6**：最终提交；保留回滚开关。

若允许多次提交：先交安全基线锁“更早提交”tie-break；再交 UNDERWRITER。若只允许一次：单任务通道打磨后再交。

### 7.1 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 技能卡/证书只离线生成；线上只有 VLA + 规则 | 最低 | 保守备选 |
| C2 确定性控制器 | 技能卡数据库 + 固定公式证书 + 规则承保；无学习权重 | 低；需说明 | 主推 |

### 7.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定为第二个模型 | C1/C2/C3；提交材料写清楚；技能卡是数据库、证书是固定打分、承保是规则 |
| 证书误杀 | 好 trial 被 abort | 保守阈值；承诺点前才止损；误杀率纳入目标；低置信不 abort |
| 重试破坏场景 | 第二次更差 | 只在承诺点前 retract；承诺后只恢复；最多 1 次 |
| 失败样本不足 | 证书无法校准 | 单任务通道 + 仿真扰动；样本 <30 只做排序，不声称概率 |
| 技能卡召回错 | 用错目标位姿 | 角色过滤 + top-k 重排 + margin 门；低置信回退 VLA |
| 开放词汇过度承诺 | 新类别失败 | 明确只覆盖“同类新外观/新说法”；无卡回退并记账 |
| 计划一致性惩罚多峰 | 正确但多样的计划被低分 | 只降权不判死；用 top-k 变体保留多样性 |
| 180s timeout | 重试耗尽时间 | 预留 `t_retry + safety`；平均时长监控；p99 门 |
| 端口串扰 | N 端口互相污染 | 每端口独立状态/账本；共享只读技能卡/模型权重 |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |
| 榜单误导 | 用合成分数校准 | 榜单只作预览；证书校准只用单任务通道/仿真 |

## 8. 与 R10–R12 的接口

| 轮次 | 层 | R13 接口 |
|---|---|---|
| R10 FACT-VLA | 相位化 BC、CAC 柔顺、EGP 证据门控 | 技能卡 phase/动作先验；证书的 phase FSM |
| R11 GEO-RESIDUAL | 动作条件化残差、米制距离、编辑检测 | 证书的 `r_edit/r_geom`；承诺后恢复 |
| R12 CHUNK-SERVO | 30 步规划 + 5 步伺服 + 相对目标 | `V1/V2` 执行层；证书决定 servo on/off |
| **R13 UNDERWRITER** | **技能选择/成功率证书/止损/回溯** | **在 R12 之上加决策层** |

`get_action` 组合：

```text
obs -> OV resolver -> variants
    -> pre-certificate -> underwriting choose
    -> WLA 30-step plan -> R12 5-step servo
    -> post-certificate -> continue/abort/recover
    -> 5-step action + token
```

## 9. 伪代码

```python
class UnderwriterPolicy:
    def __init__(self, cards, certificate, vla, servo, config):
        self.cards = cards
        self.cert = certificate
        self.vla = vla
        self.servo = servo
        self.cfg = config
        self.reset()

    def reset(self):
        self.plan = None
        self.plan_idx = 0
        self.variant = None
        self.phase = "init"
        self.committed = False
        self.retries = 0
        self.claims = []
        self.t0 = None

    def get_action(self, obs):
        self._tick(obs)
        if self.t0 is None:
            self.t0 = obs.timestamp

        if self.variant is None:
            self.variant = self._underwrite(obs)

        if self.plan is None:
            self.plan = self._plan(obs, self.variant)
            self.plan_idx = 0

        if self.committed or self.variant.kind == "V0":
            a = self._slice_plan(self.plan, self.plan_idx)
        else:
            a = self._servo_chunk(obs, self.plan, self.plan_idx)

        self.plan_idx += self.cfg.H_c
        if self.plan_idx >= len(self.plan):
            self.plan = None

        cert = self.cert.post(obs, self.variant, self.phase)
        if self._should_abort(cert, obs):
            self._abort(obs)
            a = self._safe_retract(obs)
        elif self._should_recover(cert):
            self.phase = "recover"
            a = self._recover(obs)

        return self._to_api(a, obs)

    def _underwrite(self, obs):
        variants = self._variants(obs)
        for v in variants:
            v.p_lower = self.cert.pre(v, obs)
            v.cost = self._estimate_cost(v)
            v.time = self._estimate_time(v)
        feasible = [v for v in variants
                    if v.time + self.cfg.retry_reserve <= self._remaining(obs)]
        pool = feasible or variants
        return max(pool, key=lambda v: v.p_lower - self.cfg.lam * v.cost)
```

关键点：

- `_underwrite` 只在 trial 开始/重试时调用；不是每个 chunk 重新选技能（避免抖动）。
- `_should_abort` 只在承诺前；承诺后走恢复。
- `_abort` 记录 claim、retract、选下一个变体；最多 1 次。
- 任何异常返回安全 hold/retract；不返回 NaN。
- `_to_api` 复用 R12 adapter：WLA 54D → 挑战赛 21D，`pivot` 先验证。
