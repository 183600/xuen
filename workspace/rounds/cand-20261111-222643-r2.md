# 第 55 轮（承接第 54 轮 v31 GroundEdge-GenSim+++；灵感循环第 6 轮；本轮灵感：「力控」×「机器人」）

> 第 54 轮把技能组合提升为动作空间上的可判定路径搜索，并给出动作-鲁棒性联合证书 J。但该框架默认动作是"运动学"的：位置/速度/轨迹可执行即可。真实机器人（轴孔装配、打磨去毛刺、协作搬运、插拔连接器）的关键失败往往不在运动学，而在**接触力**：同一轨迹在不同阻抗参数、不同工件刚度/摩擦下，会从"轻柔贴合"变为"顶死、打滑、颤振"。本轮把动作空间 A 扩展为**动作-力混合空间 A^F = A × W × Z**，核心矛盾是 **H22：运动学兼容 ≠ 力兼容**（两技能轨迹可拼，但扳手锥不交、阻抗不连续、接触状态跳变导致接触失稳），以及 **H23：力环实时性与云边时延的根本冲突**（1 kHz 力内环不能跨云，云端的能力证书必须在边端力域中重新落地）。

## 0. 直觉与动机

**灵感 1（从动作占用到力占用：技能 = 运动剖面 + 扳手能力包络）**
直觉：一个技能不只是在动作空间上"占了哪些位置"，还在于它能在这些位置上"施加/承受多大的力"。同样是"向下移动 2cm"，位置控制是硬碰硬，阻抗控制是柔性贴合，力控是恒力压紧——三者的运动轨迹几乎一样，接触后果完全不同。因此把第 54 轮的 `α_S : A→[0,1]` 升级为双剖面 `(α_S, β_S)`，其中 `β_S(q,w,z)` 描述在构型 q、任务扳手 w、阻抗参数 z 下技能的可执行度。技能第一次同时拥有"运动占用"与"力占用"两个身份。

**灵感 2（运动学兼容 ≠ 力兼容：把扳手锥相交作为组合的第一性约束）**
直觉：两个技能在轨迹上可以无缝拼接，不代表接触力能平滑过渡。打磨技能 S1 以 20N 法向力压紧，抓取技能 S2 只能承受 5N 的切向力，拼接后工件会被推飞；或者 S1 的高刚度阻抗与 S2 的低刚度阻抗直接切换，接触瞬间产生冲击。故组合必须同时检查：**扳手锥交集非空**、**阻抗连续**、**接触状态切换的力跳变有界**。力兼容性成为与运动兼容性并列、甚至更硬的约束。

**灵感 3（力环必须边缘化：能力包络上云，力矩闭环下沉）**
直觉：力控内环通常需要 1 kHz 以上，而云边往返 20–50 ms 已经跨越了多个接触时间常数。让云端直接闭环力，等价于用"慢相机"去接"快球"。正确分工是：**云端只上送/下发低频的"力能力包络"与任务级力序列**（在不确定接触参数集上鲁棒地算好），**边端以 1 kHz 跑阻抗/导纳控制与无源性能量罐**，只有离散的接触事件（接触建立、打滑、力越界、失稳）才回传云端触发重规划。这把第 54 轮"云规划-边校验-反向解释"的闭环在时间尺度上做了**频带分离**。

**灵感 4（无源性/能量罐是接触稳定的硬护栏，不是软指标）**
直觉：接触失稳（颤振、极限环、顶死）本质是控制器向环境持续注入能量。任何基于仿真的力证书都可能因摩擦/刚度模型误差而乐观，而**无源性**是可以在边端实时观测、且不依赖精确环境模型的硬约束：能量罐只允许"先储存、后释放"，一旦罐空就立即回退。于是力证书分两层：一层是**模型层的力裕度**（可解释、可规划），一层是**运行时的无源性监督**（不可协商、失效即安全退让）。

**灵感 5（力域迁移证书：sim-to-real 的摩擦、刚度、传感偏置鲁棒）**
直觉：力比位置更难迁移。位置误差 1mm 还能靠视觉纠偏，力误差 1N 可能就是压碎或打滑。真实接触参数（摩擦系数 μ、工件刚度 K_e、阻尼、力传感器零偏/温漂）只能在有限范围内标定。因此力证书必须在一个**不确定集 Θ** 上做最坏情况验证，并显式输出 sim-to-real 的力残差上界 `δ_f`；超过预算就拒绝部署，而不是"先跑跑看"。

**灵感 6（金字塔再加一层力层 𝔽）**
直觉：在第 54 轮的动作协同层 `𝔸` 之上叠加 **力层 `𝔽`**：`𝔽_0` 关节力矩/摩擦极限，`𝔽_1` 技能扳手能力包络，`𝔽_2` 接触状态与无源性，`𝔽_3` 任务级力序列。跨层证书同时携带 `ρ`（鲁棒性谱）、`A_cert`（动作占用）、`F_cert`（力占用），形成 **动作-力-鲁棒性三证书**。至此，"技能可组合"必须同时通过运动、力、鲁棒性三道门。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（混合动作-力空间与技能力剖面）**
混合空间 `A^F = A × W × Z`，其中 `A` 为第 54 轮动作空间，`W ⊆ ℝ^6` 为任务空间扳手（力+力矩），`Z = {(K,D) : K,D ≻ 0}` 为阻抗参数空间。技能 `S` 的力剖面 `β_S : A^F → [0,1]`，`β_S(q,w,z)=λ` 表示在最坏方向缩放到 `λ` 倍仍可行。技能形式化为 `S = (π_S, α_S, β_S, W_S)`，`π_S` 为控制律，`W_S` 为标称扳手能力包络。

**定义 122（扳手可行锥与力鲁棒裕度）**
接触集 `C`、摩擦系数 `μ`，摩擦锥 `FC_i(μ) = {f_i : ‖f_{i,t}‖ ≤ μ f_{i,n}, f_{i,n} ≥ 0}`。构型 `q` 下可达扳手锥
```
W_C(q,μ) = { w = Σ_i G_i(q) f_i : f_i ∈ FC_i(μ) } ∩ { w = J(q)ᵀτ : τ_min ≤ τ ≤ τ_max }
```
其中 `G_i` 为接触映射，`J(q)` 为雅可比。给定轨迹 `ξ` 与期望扳手 `w_d(t)`，**力鲁棒裕度**
```
ρ^F_S(ξ; μ) = max{ λ ≥ 0 : λ·w_d(t) ∈ W_C(q(t),μ), ∀t ∈ ξ }
```
部署要求 `ρ^F_S ≥ 1 + ε_safe`（ε_safe 为安全余量）。`ρ^F` 是构型相关的，不能只在端点评估。

**定义 123（力兼容性）**
技能 `S_i,S_j` 在共享接触/构型上的力兼容性由三元组判定：
```
compat_W(S_i,S_j) = vol(W_i ∩ W_j) / vol(W_i ∪ W_j) ≥ θ_w
‖K_i − K_j‖_F ≤ ε_K  ∧  ‖D_i − D_j‖_F ≤ ε_D            （阻抗连续）
‖w(C_i → C_j)‖ ≤ w_safe  ∧  τ_trans ≤ τ_c               （接触切换有界）
```
三者同时成立才记为 `force_compat(S_i,S_j)=1`。注意 `compat_W` 必须在**任务相关子空间**上算，否则无关方向的锥体积会稀释判据。

**定义 124（力感知技能组合图）**
`G^F_S = (V,E)`，`V` 为混合技能，`E = {(i,j) : motion_compat(S_i,S_j) ∧ force_compat(S_i,S_j)}`。每条边附带力组合证书
```
C^F_comp = (W_overlap, ρ^F_comp, m_pass, ΔC, γ_ce)
```
其中 `ρ^F_comp` 为力裕度沿路径的最坏传播，`m_pass` 为切换过程能量罐最小裕度，`ΔC` 为接触状态变化，`γ_ce` 沿用第 54 轮云边映射。

**定义 125（云边力契约）**
`C^F_ce = (F_env_c, F_env_e, E_contact, Fallback)`：
- `F_env_c`：云端在接触参数不确定集 `Θ` 上鲁棒计算的力能力包络（每技能/每相位的 `W` 与 `ρ^F` 下界）；
- `F_env_e`：边端 1 kHz 实际可执行的包络，要求 `F_env_e ⊇ F_env_c` 在核心扳手子空间上成立；
- `E_contact`：事件触发信道，只传离散事件 `(contact_established, slip, wrench_out, passivity_low, force_residual)`；
- `Fallback`：边端在包络越界或能量罐耗尽时的局部安全退让（退让轨迹不依赖云端）。
契约要求：`∀θ_c∈Θ, w_d(t) ∈ F_env_c ⇒ w_d(t) ∈ W_C(q(t),θ_c)` 且 `m_pass ≥ 0`（以置信度 `1−ε_θ`）。

**定义 126（力-接触联合证书）**
```
J^F = (ρ, ρ^F, α, β, W_env, m_pass, δ_f, γ_ce, evidence)
```
- `ρ`：第 53/54 轮鲁棒性谱；`ρ^F`：力鲁棒裕度；
- `α,β`：动作与力剖面；`W_env`：鲁棒扳手包络；
- `m_pass = min_t E_tank(t)`：无源性裕度；
- `δ_f = sup_{θ_c∈Θ} ‖w_real − w_sim‖`：力域迁移残差；
- `evidence` 至少包含力锥标定、接触参数采样、能量罐轨迹、边端事件日志。
可部署条件：`dom_J(T)=in`、`ρ^F ≥ 1+ε_safe`、`m_pass ≥ 0`、`δ_f < Θ_f`。

### IP-121 FSC（Force Space Characterization）

```python
def force_profile(skill, traj, W_grid, contact_model, n_mc=2000):
    beta, cones = {}, {}
    for q, w_task in traj.sample():
        Wq = reachable_wrench_polytope(skill.J(q), skill.tau_min, skill.tau_max)
        Wq = (Wq.intersect(friction_cone(contact_model.mu))
                 .intersect(unilateral(contact_model))
                 .intersect(cop_polygon(contact_model)))
        cones[q] = Wq
        for w in W_grid:
            beta[(q, w)] = normalized_margin(Wq, w)   # 0..1，边界为 0
    rho_F = min(normalized_margin(cones[q], w_task[q]) for q in traj)
    return ForceProfile(beta, cones, rho_F)
```

### IP-122 FSCG（Force-aware Skill Composition Graph）

```python
def force_compatible(s1, s2, theta_w, eps_K, eps_D, w_safe, contact):
    W1, W2 = s1.force.cones, s2.force.cones
    inter = mc_volume_lp(W1.intersect(W2), n=2000)
    union = mc_volume_lp(W1) + mc_volume_lp(W2) - inter
    compat_w = inter / max(union, 1e-9)
    dK = norm(s1.impedance.K - s2.impedance.K)
    dD = norm(s1.impedance.D - s2.impedance.D)
    dw = contact_transition_wrench(contact)     # 接触集切换的力跳变
    return (compat_w >= theta_w and dK <= eps_K and dD <= eps_D
            and dw <= w_safe)

def build_force_composition_graph(skills, theta_a, theta_w, eps_K, eps_D, w_safe):
    G = nx.DiGraph()
    for i, s1 in enumerate(skills):
        for j, s2 in enumerate(skills):
            if i == j: continue
            if not motion_compatible(s1, s2, theta_a): continue   # 第 54 轮 SCOM
            if not force_compatible(s1, s2, theta_w, eps_K, eps_D, w_safe, contact_ij):
                continue
            rho_F = compose_force_margin(s1.force, s2.force)      # 最坏传播
            m_pass = upper_bound_energy_draw(s1, s2)
            G.add_edge(i, j, compat_w=compat_w, rho_F=rho_F,
                       m_pass=m_pass, cost=cost_align_force(s1, s2))
    return G
```

```python
def cloud_force_envelope(skill_seq, Theta, eps_conf=0.05, n_scn=200):

def edge_force_execute(F_env, robot, dt=1e-3):
    pso, events = EnergyTank(alpha=0.8), []
    for phase in contact_phases(F_env):
        robot.set_impedance(phase.K, phase.D)
        for _ in range(phase.n_ticks):
            w, v = robot.read_wrench(), robot.velocity()
            if not F_env[phase.skill].contains(w):
                robot.safe_retract(); return ('contact_event', 'wrench_out', w)
            pso.update(w, v, dt)
            if pso.margin() < 0:
                robot.safe_retract(); return ('contact_event', 'passivity_low', w)
            robot.step_impedance(dt)
        if phase.contact_change:
            events.append(ContactEvent(phase.id, w, pso.margin()))
    return ('ok', pso.min_margin(), events)   # events 低频回传云端
```

### IP-126 PSO（Passivity Safety Observer）

```python
class EnergyTank:
    def __init__(self, alpha=0.8):
        self.E, self.alpha, self.E_min = 0.0, alpha, 0.0
    def update(self, w, v, dt):
        p_in = -dot(w, v)                       # 环境注入功率
        self.E += self.alpha * max(0.0, p_in) * dt
        self.E -= max(0.0, -p_in) * dt          # 只允许耗散，不允许瞬时抽取
        self.E = max(0.0, self.E)
        self.E_min = min(self.E_min, self.E)
    def margin(self):
        return self.E
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| FSC | O(T·(LP(n_c)+N_W)) | O(T·N_W) | 扳手锥线性化误差 ≤ ε_l、采样覆盖 |
| FSCG | O(|S|²·(T·LP + N_mc)) | O(|S|² + |E|) | 力锥交集 sound、成本单调 |
| CEFC | O(|Θ|·|S|·T·LP) | O(|S|·T) | 围栏在 Θ 上鲁棒、频带分离 |
| FCC | O(|Θ|·|S|·T) | O(|S|·T) | 能量罐离散无源、δ_f 预算闭合 |
| FTR | O(|Θ|·|S|) | O(|S|) | 能力映射保守、Θ 覆盖目标机型 |
| PSO | O(1)/tick | O(1) | 能量守恒、dt 满足离散无源性 |

**正确性定理（Force-Aware Contact Composition Soundness）**
假设第 54 轮 (A22)–(A28) 成立；新增 **(A29)** 摩擦锥线性化误差 ≤ ε_l 且 `W_C` 为真实可行扳手集的外近似；**(A30)** 能量罐离散化步长 `dt` 满足离散无源性，且 `m_pass<0 ⇒ 已回退`；**(A31)** 真实接触参数 `θ_c ∈ Θ`，标定覆盖率 ≥ `1−ε_θ`；**(A32)** 边端力事件延迟 ≤ `τ_event`，云端围栏更新为事件触发且不回环进力内环。
则接触安全概率满足
```
P_safe ≥ 1 − ε_θ − P(δ_f > Θ_f) − P(m_pass < 0 | Θ) − Σ_d (1 − ρ_min(d)) − P(contact_event missed)
```
关键：**力兼容先行、力环边缘化、无源性硬护栏、Θ 上最坏情况验证**。

## 6. 本轮最大风险

**一句话**：把技能组合从"动作-鲁棒性双证书"推进到"动作-力-鲁棒性三证书"是必要的，但其 soundness **三重依赖扳手锥模型的保真度、无源性监督在传感噪声下的保守性、以及接触参数不确定集 Θ 对真实工件/机型的覆盖**；一旦锥模型系统性乐观或 Θ 漏掉真实摩擦/刚度，证书就会把"力域可对齐假象"当成部署前提，在真实接触中表现为顶死、打滑或颤振并造成硬件损伤，故必须以 **接触参数在线标定 + 能量罐硬护栏 + 保守力围栏** 三道不可协商的护栏兜底，宁可牺牲一点柔顺效率，也绝不让力证书越过无源性边界。

> - **FSC（Force Space Characterization）**：技能力剖面 `β_S` 与扳手能力包络 `W_C(q,μ)`；
> - **FSCG（Force-aware Skill Composition Graph）**：运动+力双重兼容的技能组合图；
> - **CEFC（Cloud-Edge Force Coordination）**：云端鲁棒力围栏 + 边端 1 kHz 力内环的频带分离；
> - **FCC（Force-Contact Certificate）**：力-接触联合证书 `J^F`；
> - **FTR（Force Transferability Residual）**：跨机型/跨工件的力域迁移证书与残差界 `δ_f`；
> - **PSO（Passivity Safety Observer）**：无源性能量罐运行期硬护栏。
>
> IP 编号：IP-121~IP-126（共 6 个新增），升级 IP-115/116/117/118 以纳入力维度。

### IP-121 FSC

```python
def force_profile(skill, traj, W_grid, contact_model):
    beta, cones = {}, {}
    for q, w_task in traj.sample():
        Wq = reachable_wrench_polytope(skill.J(q), skill.tau_min, skill.tau_max)
        Wq = (Wq.intersect(friction_cone(contact_model.mu))
                 .intersect(unilateral(contact_model))
                 .intersect(cop_polygon(contact_model)))
        cones[q] = Wq
        for w in W_grid:
            beta[(q, w)] = normalized_margin(Wq, w)
    rho_F = min(normalized_margin(cones[q], w_task[q]) for q in traj)
    return ForceProfile(beta, cones, rho_F)
```

### IP-122 FSCG

```python
def force_compatible(s1, s2, theta_w, eps_K, eps_D, w_safe, contact):
    W1, W2 = s1.force.cones, s2.force.cones
    inter = mc_volume_lp(W1.intersect(W2), n=2000)
    union = mc_volume_lp(W1) + mc_volume_lp(W2) - inter
    compat_w = inter / max(union, 1e-9)
    return (compat_w >= theta_w
            and norm(s1.K - s2.K) <= eps_K
            and norm(s1.D - s2.D) <= eps_D
            and contact_transition_wrench(contact) <= w_safe)

def build_force_composition_graph(skills, theta_a, theta_w, eps_K, eps_D, w_safe):
    G = nx.DiGraph()
    for i, s1 in enumerate(skills):
        for j, s2 in enumerate(skills):
            if i == j: continue
            if not motion_compatible(s1, s2, theta_a): continue
            if not force_compatible(s1, s2, theta_w, eps_K, eps_D, w_safe, contact_ij):
                continue
            G.add_edge(i, j,
                       rho_F=compose_force_margin(s1.force, s2.force),
                       m_pass=upper_bound_energy_draw(s1, s2),
                       cost=cost_align_force(s1, s2))
    return G
```

### IP-123 CEFC

```python
def cloud_force_envelope(skill_seq, Theta, eps_conf=0.05, n_scn=200):
    samples = scenario_sample(Theta, n=n_scn)
    curves = [(s.id, force_profile(s, s.traj, s.W_grid, theta))
              for theta in samples for s in skill_seq]

                              confidence=1 - eps_conf) for sid in skill_seq}
    return CloudForcePlan(skill_seq, F_env)

def edge_force_execute(F_env, robot, dt=1e-3):
    pso, events = EnergyTank(alpha=0.8), []
    for phase in contact_phases(F_env):
        robot.set_impedance(phase.K, phase.D)
        for _ in range(phase.n_ticks):
            w, v = robot.read_wrench(), robot.velocity()
            if not F_env[phase.skill].contains(w):
                robot.safe_retract(); return ('contact_event', 'wrench_out', w)
            pso.update(w, v, dt)
            if pso.margin() < 0:
                robot.safe_retract(); return ('contact_event', 'passivity_low', w)
            robot.step_impedance(dt)
        if phase.contact_change:
            events.append(ContactEvent(phase.id, w, pso.margin()))
    return ('ok', pso.min_margin(), events)
```

```python
def force_contact_certificate(skill_seq, Theta, delta_f_budget, rho_F_min):
```

```python
def force_transfer_certify(cert_src, robot_target, Theta_target, delta_f_budget):
    W_shift = wrench_capability_shift(cert_src.W_env, robot_target)
    rho_F_t = project_force_margin(cert_src.rho_F, W_shift, Theta_target)
```

### IP-126 PSO

```python
class EnergyTank:
    def __init__(self, alpha=0.8):
        self.E, self.alpha, self.E_min = 0.0, alpha, 0.0
    def update(self, w, v, dt):
        p_in = -dot(w, v)
        self.E += self.alpha * max(0.0, p_in) * dt
        self.E -= max(0.0, -p_in) * dt
        self.E = max(0.0, self.E)
        self.E_min = min(self.E_min, self.E)
    def margin(self):
        return self.E
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| FSC | O(T·(LP(n_c)+N_W)) | O(T·N_W) | 锥外近似 sound、采样覆盖 ≥ 95% |
| FSCG | O(|S|²·(T·LP+N_mc)) | O(|S|²+|E|) | 双重兼容、路径最优 |
| CEFC | O(|Θ|·|S|·T·LP) | O(|S|·T) | 围栏鲁棒、事件不回环内环 |
| FCC | O(|Θ|·|S|·T) | O(|S|·T) | 能量罐无源、δ_f 预算闭合 |
| FTR | O(|Θ|·|S|) | O(|S|) | 能力映射保守、Θ 覆盖目标 |
| PSO | O(1)/tick | O(1) | 离散无源、越界即退让 |

**正确性定理（Force-Aware Contact Composition Soundness）**
承接第 54 轮 (A22)–(A28)；新增 **(A29)** 摩擦锥线性化误差 ≤ ε_l 且 `W_C` 为真实可行扳手集外近似；**(A30)** 能量罐满足离散无源性，`m_pass<0 ⇒ 已安全退让`；**(A31)** 真实接触参数 `θ_c∈Θ`，覆盖率 ≥ `1−ε_θ`；**(A32)** 力事件延迟 ≤ `τ_event`，云端围栏事件触发且不进力内环。
则：
```
P_safe ≥ 1 − ε_θ − P(δ_f > Θ_f) − P(m_pass < 0 | Θ) − Σ_d(1 − ρ_min(d)) − P(contact_event missed)
```
关键：**力兼容先行、力环边缘化、无源性硬护栏、Θ 上最坏情况验证**。

## 6. 本轮最大风险

**一句话**：动作-力-鲁棒性三证书的 soundness **三重依赖扳手锥模型保真度、无源性监督在传感噪声下的保守性、以及接触参数不确定集 Θ 的覆盖**；一旦锥模型系统性乐观或 Θ 漏掉真实摩擦/刚度，证书会把"力域可对齐假象"当成部署前提，在真实接触中表现为顶死、打滑或颤振并损伤硬件，故必须以 **接触参数在线标定 + 能量罐硬护栏 + 保守力围栏** 三道不可协商的护栏兜底，宁可牺牲柔顺效率，也绝不让力证书越过无源性边界。
