# 第 43 轮（新循环第 3 轮） · 证书联邦：把多任务学习从「共享参数」升级为「共享可认证骨干 + 逐任务干扰预算」（四层架构 v8）

> 承接第 42 轮 v19（SCV × CKB × ECR 飞轮）。第 42 轮自陈最大风险是「仿真偏差累积 + 检索幻觉」，本质是**验证链路的不确定性**。本轮灵感词「创新点」「多任务学习」击中另一个更根本的命门：UniBot 要展示的从来不是单一技能，而是**一个本体、多种任务**；而第 41–42 轮的所有证书都是「单任务独立认证」，任务数一多，认证成本线性爆炸、且无法解释「共享模型为什么没有互相拖垮」。多任务学习（MTL）正是工业界解决该问题的标准答案，但它也是**安全认证的天敌**——负迁移会让某个任务的边际在共享表示里悄悄塌陷。本轮的核心主张：**不要逐任务认证，也不要盲信共享；把「共享」本身做成一张可认证的证书**，即「证书联邦」（Certificate Federation）：一条共享骨干的证书 C_0 被 K 个任务复用，每个任务只增量认证「干扰税」Δ_τ，并用任务亲和图决定谁有资格共享。

## 0. 直觉与动机

**灵感 1（多任务学习 → 一根骨干，K 张证书）**：单任务认证的直觉是「每加一个任务，就重跑一遍全量仿真 + CEGAR + 量化」，成本 O(K·|X|)。MTL 的直觉是：UniBot 的导航、抓取、操作、交互共享同一套视觉/几何/动力学表征，共享骨干只需认证一次，任务头是低维增量。于是认证成本从 O(K·|X|) 变为 O(|X| + Σ|head_τ|)——这正是第 42 轮 L0/L1 边缘化思路在「任务维度」上的对偶：**离线认证一次骨干，在线复用给所有任务**。但共享也意味着「一损俱损」，必须显式度量每个任务被其他任务「污染」了多少。

**灵感 2（负迁移 = 证书税，必须被预算）**：MTL 的经典失效是负迁移（negative transfer）：任务 A 的梯度把共享表示拉向对 B 无用的方向，B 的安全边际随之下降。直觉上，这等价于给任务 τ 的证书加了一笔「税」Δ_τ；只要 τ 在单任务参考下留有余量 σ_τ = m_lo^STL − θ_τ，且 Δ_τ ≤ σ_τ，则共享后证书仍然 sound；反之就是不可接受的负迁移，必须拆组或加宽头容量。这把「MTL 好不好」从调参玄学变成一个**可测量、可预算、可熔断**的证书量。

**灵感 3（创新点 → 从「堆 IP」到「可测量的新机制」）**：本文件的母题就是「寻找参加 UniBot 的创新点」。前 42 轮已堆出 56 个 IP，但评审不会为 IP 数量买单，只会问：**哪一个机制是别人没有、且能被硬指标证明的？** 本轮的创新点不是再加一个模块，而是把「多任务共享」从工程技巧升格为「可认证对象」。直觉判据：一个真正的创新点必须同时满足四件事——机制与基线不同（M）、有可测增益（G）、有不可替代性（U）、有红线实验（E）。本轮引入「创新点账本」把这些显式化，避免「创新点通胀」。

**耦合**：第 42 轮的 CKB 从「单任务案例库」升级为「跨任务亲和检索」——检索相似任务的历史干扰数据，直接预测新任务该不该并入哪个共享组；SCV 增加「干扰压力测试」；ECR 变成「共享 INT8 骨干 + K 个任务头」；CAR 的状态空间从 (mode) 扩为 (task, mode)，并新增「任务切换」转移边。证书由此从「单任务飞轮」升级为「多任务联邦」。

## 1. 形式化定义（增量：定义 38–44）

**定义 38（任务族、共享骨干与任务头）**：设任务族 T = {τ_1,…,τ_K}，每个任务有数据分布 D_τ 与安全约束 S_τ。多任务策略分解为
π_τ(a|x) = h_{φ_τ}( f_θ(x) )，
其中 f_θ: X → Z 为共享骨干（编码器），h_{φ_τ}: Z → Δ(A) 为策略头。联合训练目标
L_MTL(θ,{φ_τ}) = Σ_τ w_τ [ L_τ(h_{φ_τ}∘f_θ) + λ·L_cert,τ ]，
L_cert,τ = E_{x∼D_τ} max(0, θ_τ − m_τ(x))，m_τ(x) = g_{ψ_τ}(f_θ(x), x)。
关键结构约束：共享只发生在表征层，证书头 g_{ψ_τ} 保持**按任务的单调解码**，从而「共享」不改变每个任务的 soundness 语义，只改变其边际数值。

**定义 39（任务条件证书与证书联邦）**：任务 τ 的证书 C_τ = (Inv_τ, θ_τ, L_{m,τ}, T_{hold,τ}, {α_{e,τ}})。定义共享骨干证书
C_0 = ( Lip(f_θ), B_z, D_z )，
其中 Lip(f_θ) 为表示 Lipschitz 常数，B_z 为表示漂移界，D_z 为表示覆盖域。**证书联邦** F = (C_0, {C_τ}_{τ∈T})。soundness 要求：对每个 τ，在 C_τ 有效域上 m_τ(x) ≥ θ_τ。C_0 被所有任务复用，故 F 的验证成本是「骨干一次 + 任务头增量」，而非 K 次全量。

**定义 40（表示漂移、干扰证书与负迁移判据）**：以第 42 轮单任务教师骨干 f_{θ_τ} 为参考，定义表示漂移
R_τ = sup_{x∈D_τ} ‖ f_θ(x) − f_{θ_τ}(x) ‖_2。
若证书头对 z 为 L_{g,τ}-Lipschitz，则**跨任务干扰上界**
Δ_τ ≜ sup_x | m_τ^MTL(x) − m_τ^STL(x) | ≤ L_{g,τ}·R_τ + ε_head。
定义**干扰预算（证书余量）** σ_τ = m_lo,τ^STL − θ_τ。判据：
- Δ_τ ≤ σ_τ ⟹ 正迁移可认证，共享后仍满足 m_τ^MTL ≥ θ_τ；
- Δ_τ > σ_τ ⟹ 负迁移，必须拆组 / 增宽任务头 / 提高训练权重。
等价地，若坚持复用单任务证书，则须以 θ'_τ = θ_τ + Δ_τ 重新核对 C_τ^STL——**共享的代价被显式记账为阈值抬升**。

**定义 41（任务亲和图与受约束分组）**：构造加权图 G_aff = (T, E, w)，边权
w_{ij} = G_{ij} − λ_D · max(Δ_{i|j}, Δ_{j|i})，
其中 G_{ij} 为联合训练的可测增益（互信息 / 梯度余弦 / 样本效率），第二项为相互干扰代价。分组问题为
max_{partition {S_m}} Σ_m Σ_{i,j∈S_m} w_{ij}
s.t. ∀τ∈S_m: Δ_τ(S_m) ≤ σ_τ，且 |S_m| ≤ N_max。
这是带背包约束的相关聚类（NP-hard）；工程上用谱聚类 + 贪心可行化，并允许「单任务组」作为兜底——**不可共享的任务必须能被显式隔离**。

**定义 42（证书复用率）**：V(STL) = Σ_τ c(C_τ^STL)，V(Fed) = c(C_0) + Σ_τ c(C_τ^inc)。复用率 ρ = V(STL)/V(Fed)。当 c(C_0) 对 K 次线性、且任务头证书增量远小于全量证书时，ρ 随 K 增长——这是 MTL 在「认证经济学」上的核心收益，也是本创新点可量化的卖点。

**定义 43（任务切换与任务合取证书）**：运行时刻 t_s 从 τ_i 切到 τ_j，定义**瞬态证书** C_{ij}^sw：对 t∈[t_s, t_s+T_switch]，要求
m_{τ_i}(x_t) ≥ θ_{τ_i} ∨ m_{τ_j}(x_t) ≥ θ_{τ_j}，
即「旧任务仍安全」或「新任务已接管」二者必居其一，切换守卫 ψ_{ij}(x) 保证不落入两者皆不安全的瞬态盲区。对同时多目标任务（如「边走边抓」）τ_i ∧ τ_j，除两任务各自阈值外，还需交叉干扰约束 |m_{τ_i} − m_{τ_i|τ_j}| ≤ β_{i|j}；其乘积自动机模板复用第 42 轮 IP-47 的 KB 预存片段。

**定义 44（创新点账本与创新度判据）**：每条创新主张记为创新点卡 IC = (M, B, G, U, E)：M=机制（与何基线不同），B=基线，G=可测增益，U=不可替代性论证（去掉该机制后哪个硬门槛必然失败），E=验证实验编号。创新度
N(IC) = [G 达成 ∧ U 成立] · log(1 + Δ_perf/Δ_cost)。
N=0 的主张一律降级为「工程实现」，不得进入创新点清单。该定义把本文件的母题「寻找创新点」本身形式化，强制每个 IP 说明「不可替代性」，直接对抗第 42 轮遗留的「IP 通胀」风险。

## 2. 四大产出设计（增量 IP-57/58/59/60 + 升级 IP-51/52/53/54/55/56/49/50/47）

### 2.1 IP-57 CMTL（Certified Multi-Task Learner，证书化多任务学习器）
1. **共享骨干 + 任务条件证书头**：骨干只输出表征 z；每个 τ 有独立策略头与证书头，证书头保持单调解码，便于逐任务审计。
2. **干扰正则训练**：在 L_MTL 上追加 L_interf = Σ_τ relu(‖f_θ(x) − f_{θ_τ}(x)‖ − σ_τ/L_{g,τ})，把表示漂移 R_τ 直接压进证书预算内——不是「希望别负迁移」，而是「优化时就把 Δ_τ ≤ σ_τ 当作约束」。
3. **干扰预算分配**：σ_τ 由第 42 轮 SCV 实测的单任务余量给出；预算紧的任务自动获得更大的干扰惩罚权重与更宽的头容量。
4. **证书头的单调保守性**：证书头沿用区间/单调结构（第 42 轮 IP-53 CMC 的可解释子网），保证蒸馏与多任务训练后仍可给出下界。

### 2.2 IP-58 TAC（Task Affinity Certificate，任务亲和证书）
1. **亲和探针**：对每对 (τ_i, τ_j) 用极小预算做联合训练探针，测增益 G_{ij} 与干扰 Δ_{i|j}, Δ_{j|i}；结果回写 CKB，避免重复探测。
2. **受约束分组**：谱聚类给出初值，贪心做可行性修复（逐组检查 Δ_τ(S_m) ≤ σ_τ），不可行则拆分；单任务组是合法解。
3. **跨任务检索**：新任务 τ_new 进来时，按任务/环境指纹从 CKB 检索历史亲和记录，预测其最优组，冷启动从「探测 K 次」降为「探测 Top-3 组」。
4. **可撤销性**：分组带版本号，一旦某任务在线干扰超预算，运行时可快速回退到单任务骨干（保留双备份）。

### 2.3 IP-59 MT-SCV（Multi-Task Sim-Cert Validator，多任务仿真证书验证器）
1. **联合域随机化**：在 D_sim 上对同组任务做**联合采样**（共享场景、共享扰动），测「同场景下两任务是否互相拆台」。
2. **干扰压力测试**：在 D_τ 的尾部/对抗样本上比较 m_τ^MTL 与 m_τ^STL，实测 Δ_τ，检验定义 40 的 Lipschitz 上界是否被突破。
3. **切换压力测试**：生成随机任务切换序列，统计瞬态盲区命中率、切换守卫覆盖率、T_switch 实际分布。
4. **共同模式故障注入**：故意污染共享骨干（量化误差、通道剪枝、单任务数据污染），测量「单点故障向其他任务传播的半径」，作为联邦相关失效的量化指标。

### 2.4 IP-60 TCM（Task-Certificate Multiplexer，任务证书多路复用器）
1. **运行时任务识别**：由上层指令 + task-id 头联合判定 τ_hat；判定不确定时退化为「所有候选任务都须满足」的保守交集。
2. **证书多路复用**：一次骨干前向 + 选中的任务头，输出 m_τ；档位沿用第 42 轮 L0 查表 / L1 INT8，多任务共享骨干使内存从 K·M 降为 M + Σm_τ。
3. **切换守卫与瞬态证书**：维护 C_{ij}^sw，切换窗口内同时评估新旧任务边际，任一侧安全即可放行，否则 SafeStop。
4. **在线干扰监控**：滑窗估计每个任务的实际边际分布，若某任务 Δ_τ 超预算，触发 TAC 重新分组并上报「联邦心跳」。

## 3. 四层架构 v8

```
L1: TRI-FUSE(INT8) + IP-49 LIO → 度量语义图 C_ms + 漂移界 B_t + 每任务 L_{m,τ}
L2: CTC + VLM + IP-35 仲裁 → R_φ(w) + 几何残差证书 → 任务指纹 φ_τ / 环境指纹 ψ
L3: IP-60 TCM(共享INT8骨干 + 任务头 + 切换守卫) ← IP-51 CAR((task,mode) 自动机)
    → IP-58 TAC(亲和分组) → IP-47 乘积模板 + 交叉干扰 β → IP-39 规划(CBF margin=m_lo,τ)
    → IP-45 总线(联邦心跳: Δ_τ/σ_τ/分组版本) → IP-48 认证流匹配 + IP-53 CMC(共享骨干+多头看门狗)
L4: IP-55 CKB(跨任务亲和检索 + 分组模板) ← IP-59 MT-SCV(联合域随机化 + 干扰/切换/共模压力测试)
    → IP-57 CMTL(干扰正则 + 逐任务 L_cert) + IP-44 蒸馏(共享骨干多头 INT8) + IP-50 多任务课程
    → RCA 重颁「联邦证书」F=(C_0,{C_τ}) → 契约热更新
运行期：骨干前向一次 + 任务头选择 + 切换守卫 → Δ_τ 在线监控 → 超预算触发重组/回退单任务骨干
```

## 4. 实验设计（E87–E94 硬门槛，承接 E79–E86）

| 实验 | 指标 | 门槛 |
|---|---|---|
| E87 干扰界有效性 | 实测 Δ_τ ≤ 定义 40 理论上界的比例；尾部（p99）超界率 | ≥95%；尾部超界 < 1% |
| E88 正迁移收益 | 达到单任务精度所需样本/仿真的加速比（≥3 任务）；负迁移任务数 | ≥1.5x；负迁移任务 = 0 |
| E89 亲和分组可行性 | 分组后每任务 Δ_τ ≤ σ_τ 的达成率；平均组规模 | 100%；2–4 任务/组 |
| E90 共享多头 INT8 运行时 | K=5 时总 RAM；单头 WCET；误 trip 率 | < 24KB；< 100μs；< 0.05% |
| E91 证书复用率 | ρ = V(STL)/V(Fed)；K=5/10 时的扩展曲线 | ≥3x（K=5）；随 K 单调升 |
| E92 任务切换安全 | 10k 次切换的不安全事件；瞬态盲区命中率 | 0 起；< 0.1% |
| E93 多任务课程收敛 | 最终 Nominal 占比；达到收敛的仿真轮数 vs 单任务串行 | ≥80%；轮数 ≤ 0.7×串行 |
| E94 UniBot 端到端多任务演示 | K≥5 任务成功率、安全违例、干涉后恢复时间 | 成功率 ≥ 基线；0 违例；< 2s |

回退：E87 干扰界失效 → 关闭共享，退回 K 个单任务骨干（联邦退化为联盟）；E88 负迁移 → 对该任务拆组或增宽任务头；E89 分组不可行 → 全部单任务组；E90 超内存 → 共享骨干量化更激进 + 任务头剪枝；E92 切换不安全 → 加长 T_switch 或强制 SafeStop 式切换；E94 演示不达标 → 减少任务数，保「可认证」叙事而非任务数量。

## 5. 本轮最大风险

**一句话**：证书联邦把 K 个原本独立的失效变成一个**共同模式失效**——共享骨干一旦被某个任务的数据污染或量化误差带偏，所有任务的边际会在同一时刻一起跌破阈值，而定义 40 的 Lipschitz 干扰界又恰恰最容易在尾部样本上低估，于是系统会在「所有证书都还显示绿色」时集体失效，这比单任务的局部降级更难定位、也更致命；因此 E87（干扰界尾部）与 E90（共享骨干共模故障）必须作为红线实验，任一不达标即回退为单任务联盟。

# 第 43 轮产物 · 创新点清单 v20：证书联邦（CMTL × TAC × MT-SCV × TCM）——共享可认证骨干 × 逐任务干扰预算（四层架构 v8）

## 2. 关键算法（伪代码）

### IP-57 CMTL：带干扰预算的多任务训练
```python
def train_cmtl(tasks, f_theta, heads, cert_heads, refs, budgets,
               theta, L_g, epochs, lambda_cert=1.0, mu=1.0):
    # refs[tau]: 第 42 轮单任务教师骨干 f_{theta_tau}（冻结）
    # budgets[tau] = sigma_tau = m_lo_STL(tau) - theta(tau)
    for epoch in range(epochs):
        for batch in multitask_loader(tasks, curriculum=interference_aware_plan()):
            z = f_theta(batch.x)
            loss = 0.0
            loss_interf = 0.0
            for tau in batch.active_tasks:
                m_tau = cert_heads[tau](z, batch.x)
                loss += batch.w[tau] * (task_loss(heads[tau](z), batch.y[tau])
                                        + lambda_cert * relu(theta[tau] - m_tau).mean())
                # 干扰正则：限制表示漂移，使 L_g*R_tau + eps <= sigma_tau
                drift = l2_norm(z[batch.mask[tau]] - refs[tau](batch.x[batch.mask[tau]]))
                loss_interf += relu(drift - budgets[tau] / max(L_g[tau], 1e-6))
            loss += mu * loss_interf
            backward(loss)
    return f_theta, heads, cert_heads

# 认证：仿射迁移界 + 尾部校准
def certify_task_mtl(tau, f_theta, cert_head, ref, theta, L_g, sigma, D_tau_probe):
    R = sup_norm(f_theta(x) - ref(x) for x in D_tau_probe)
    Delta = L_g[tau] * R + EPS_HEAD
    status = "POSITIVE_TRANSFER" if Delta <= sigma[tau] else "NEGATIVE_TRANSFER"
    return {"Delta_tau": Delta, "sigma_tau": sigma[tau],
            "theta_effective": theta[tau] + Delta, "status": status}
```

### IP-58 TAC：亲和探测与受约束分组
```python
def build_affinity_graph(tasks, KB, probe_budget, lambda_D=1.0):
    W = {}
    for i, j in combinations(tasks, 2):
        cached = KB.lookup_affinity(i, j)
        if cached:                      # 跨任务 RAG：复用历史探测
            W[i, j] = cached
            continue
        G_ij = transfer_gain_probe(i, j, budget=probe_budget)
        D_ij = interference_probe(i, j, budget=probe_budget)   # (Delta_i|j, Delta_j|i)
        W[i, j] = G_ij - lambda_D * max(D_ij)
        KB.store_affinity(i, j, W[i, j], D_ij)
    return Graph(tasks, W)

def constrained_partition(G, sigma, N_max, rounds=50):
    # 谱聚类给初值；贪心可行化：逐组检查每个任务的 Delta_tau(S) <= sigma_tau
    labels = spectral_cluster(G, k_est(G, N_max))
    for _ in range(rounds):
        moved = False
        for tau in G.nodes:
            for S in feasible_groups(labels, tau, G, sigma, N_max):
                if gain(tau, S, G) > 0:
                    labels[tau] = S; moved = True; break
        if not moved:
            break
    # 永不容忍不可行组：拆到单任务组（联盟兜底）
    return split_infeasible_groups(labels, G, sigma)
```

### IP-59 MT-SCV：干扰 / 切换 / 共同模式压力测试
```python
def stress_test_federation(federation, D_sim_multi, N_per_task=1000, N_switch=10000):
    report = {}
    for S in federation.groups:
        # 1) 联合域随机化：同一场景同时驱动组内所有任务
        joint_stats = run_joint_sim(S, D_sim_multi, N_per_task)
        # 2) 干扰压力测试：尾部/对抗样本上实测 Delta_tau
        for tau in S:
            x_adv = tail_and_adversarial(D_tau=tau, n=N_per_task)
            m_mtl = federation.cert_margin(tau, x_adv)
            m_stl = federation.single_task_ref(tau).margin(x_adv)
            Delta_emp = max_abs(m_mtl - m_stl)
            if Delta_emp > federation.sigma[tau]:
                report.setdefault('negative_transfer', []).append((tau, Delta_emp))
        # 3) 切换压力测试：随机任务切换序列
        for _ in range(N_switch):
            ti, tj = random_switch_pair(S)
            ok = run_switch_traj(ti, tj, federation.switch_guard)
            report.setdefault('switch_fail', 0)
            report['switch_fail'] += (not ok)
        # 4) 共同模式故障注入：污染共享骨干，测跨任务传播半径
        for tau in S:
            polluted = inject_fault(federation.trunk, tau)
            affected = [t for t in S
                        if trunk_cert_breaks(polluted, t)]
            report.setdefault('common_mode', {})[tau] = len(affected)
    return report
```

### IP-60 TCM：运行时多路复用与切换守卫
```python
def tcm_step(x_int8, cmd_task=None):
    z = trunk_int8(x_int8)                         # 共享骨干，一次前向
    tau_hat = cmd_task if cmd_task is not None else task_id_head_int8(z)
    m = cert_heads_int8[tau_hat](z)                # 选中任务头
    if m >= theta_int16[tau_hat]:
        mode = "NOMINAL"
    elif m >= theta_int16[tau_hat] - Delta_int16[tau_hat]:
        mode = "DEGRADED"                          # 仍在干扰预算内
    else:
        mode = "SAFESTOP"
    # 切换瞬态守卫：旧任务仍未失效 或 新任务已接管
    if tau_hat != state.tau_prev:
        if not switch_guard(state.tau_prev, tau_hat, z):
            mode = "SAFESTOP"
        state.tau_prev = tau_hat
    # 在线干扰监控：实际边际分布超出预测，触发重组/回退
    drift_monitor.update(tau_hat, m, z)
    if drift_monitor.interference(tau_hat) > sigma[tau_hat]:
        bus.publish("federation/heartbeat", {"task": tau_hat,
                    "action": "REGROUP_OR_FALLBACK", "kb_version": KB.version})
    return mode, m

def switch_guard(tau_i, tau_j, z):
    # 定义 43：m_i >= theta_i  OR  m_j >= theta_j
    m_i = cert_heads_int8[tau_i](z)
    m_j = cert_heads_int8[tau_j](z)
    return (m_i >= theta_int16[tau_i]) or (m_j >= theta_int16[tau_j])
```

# IP-51 CAR：状态=(task, mode)，任务切换边带瞬态守卫
def car_transition(e, x, federation):
    tau_i, tau_j = e.src_task, e.dst_task
    if tau_i != tau_j and not switch_guard(tau_i, tau_j, federation.encode(x)):
        return REJECT
    return federation.cert_margin(tau_j, x) >= e.alpha * e.theta_sim

# IP-52 LCS：K 任务预算调度，骨干只认证一次
def certify_light_mt(x, tasks, budget_us):
    b0 = trunk_lookup_L0(x)                       # 共享骨干查表
    order = sort_by_risk_x_criticality(tasks)     # 干扰风险 × 关键度
    out = {}
    for tau in order:
        if budget_us < 110: break
        out[tau] = monitor_head_INT8(tau, b0)     # 任务头增量
        budget_us -= 100
    return out, downgrade_monotone_mt(out)

def export_federated(shared_interval_trunk, task_heads, calib):
    trunk_onnx = shared_interval_trunk.to_onnx()

## 7. 本轮最大风险

**一句话**：证书联邦把 K 个独立失效耦合成一个**共同模式失效**——共享骨干一旦被某任务数据污染或量化误差带偏，所有任务的边际会在同一时刻一起跌破阈值，而 Lipschitz 型干扰界又恰在尾部样本上最易低估，系统会在「全部证书仍显示绿色」时集体失效，比单任务局部降级更难定位也更致命；故 E87（尾部干扰界）与 E90（共模故障）设为红线，任一不达标即回退为单任务联盟。
