# 第 1 轮（UniBot 线；本轮灵感：「云边协同」×「多视角视觉」）

> **接续说明**：上一版 UniBot 奠基版以「抓取 × 技能学习 × 地形适应」组织主线（定义 U1–U12 / 引理 L1–L7 / 实验 E601–E618）。本回合**不推翻领域事实**，而以「云边协同 × 多视角视觉」**重新组织问题**：把上一版的"三层栈 + 工程层"压缩成一个更基本的研究对象——**受截止时间与带宽约束的信息路由**。旧编号封存；本轮启用 M1–M12 / V1–V6 / E701–E720。

## 0. 情报核实（检索日期 2026-11-17，聚焦本轮相关字段）

1. **任务面**：UniBot-V1 通才赛道，Unitree G1 真机，32 项桌面操作任务，5 类泛化场景（位置 / 干扰物 / 背景 / 未见物品 / 人为干扰），按平均成功率 + 平均步骤分排名；选手自部署策略服务、经标准化远程 API 接入。
2. **传感面**：官方数据每任务一个 LeRobot v3.0 数据集（共 32 份，≈32k episodes / 169 h），4 路 480×640@30fps 相机（头 stereo 左右 + 左右腕）；Dex1 单自由度夹爪，**接口只暴露 1 维开合标量、无触觉、无手指关节**。⇒ 多视角不是额外传感器，而是**唯一可用**的几何测量手段。
3. **接口面**：`metadata` / `get_action(obs)` / `reset()`；`control_space ∈ {joint, ee}` 互斥；`action_chunk_size` 由提交方声明；`obs_delta_indices` **同时**决定"传输哪些观测"与"时序叠帧方式"；`image_resize` 由**评测端** cv2 执行；token 在 `metadata` 与每步 `meta.token` 两处校验；评测在 **N 台真机**随机顺序执行，须暴露连续端口 8765…8765+N−1；官方明确采集 per-step 延迟及其波动、返回动作的统计规律性，并可能据此评估可信度。
4. **榜单面**：`leaderboard_data.json` 是 **teaser / 占位表**（`gen_leaderboard.py` "randomly-generated"，被"即将公开"遮罩），但字段结构、任务名、模型名真实；本轮只把它当"接口与任务面的规格说明书"，数字仅作结构参考。
5. **参考架构**：官方 UnifoLM-WLA 6B VLA 报告推理 **<105 ms**。而 30 fps 的硬节拍是 **Δ = 33 ms/step** ⇒ 6B 级 VLA **无法每步同步完成**。这不是工程瑕疵，而是本轮立论的物理起点。

## 1. 直觉：两个灵感的第一性原理

### 灵感 A ·「多视角视觉」→ 单视角的失败大多是"几何不可识别"，不是"语义不懂"

**直觉**：把 4 路相机想成一台被拆散的测量仪——头 stereo 负责**全局深度**，双腕负责**接触近场**，重叠区负责**三角化与遮挡互补**。单目在光轴方向（z）本质不可观测；单视角又常被手和物体自遮挡；单帧更分不清"抓住了随臂在动"与"没抓住但臂在动"。于是"插入差一点、旋转打滑、摆放偏几毫米"这些失败，靠更大的语义模型硬猜是低效的，靠**几何一致性**去测才是对症的。

**第一性原理**：可操作的状态量是**相对量**——物体相对夹爪的 6D 变换 `T_oe`、以及它随时间的恒定性。它恰好能被多视角 + 已知 EE 位姿联合测出：静止时 `T_oe` 恒定；打滑时 `T_oe` 漂移；对齐时 `T_oe` 趋近目标。**"抓住没有""滑没滑""插没插进去"都可以统一成 `T_oe`（及其导数）的判据**，而不是三个各自为政的检测器。

**推论**：最难的插入 / 旋转任务应交给**几何闭环（相对位姿伺服）**，让语义 VLA 负责"选哪个物体、去哪个区域、用哪种技能"，二者分工而非互相替代。

### 灵感 B ·「云边协同」→ 延迟不是要消灭的噪声，而是可分配的预算

**直觉**：6B VLA 的 80–105 ms 推理，撞上 33 ms/step 的硬节拍，如果每步都同步等云端，必然超时。但接口是按 **action chunk** 交接的：一块动作执行期间 `T_a·Δ`，正好是下一块的**异步计算窗口**。也就是说——**chunk 长度就是云端的算力预算**（`T_a=8` 时约 264 ms，`T_a=2` 时只有 66 ms）。于是"慢而准"的云端和"快而糙"的边缘可以共存：云端低频下发**意图**（子目标 / 相对位姿 / 技能 latent），边缘高频生成**动作**并在本地闭环兜底。

**第一性原理**：在一个受审计的远程评测里，真正的设计变量不是"云端模型多强"，而是每一次决策的 **(看哪些视角、传多少字节、在哪一层算、chunk 多长)**。延迟与带宽是**预算**，不是误差项；我们做的是**信息路由**，不是"把模型压小"。

**推论**：精度相位（抓握 / 对齐 / 插入）需要短 chunk 与高频反馈，会把云端预算掐死 ⇒ 这些相位必须**边缘主导、云端预取**；搬运 / 大范围移动相位可用长 chunk，让云端主导。**分工随相位切换**。

### 合成：DBC-IR（Deadline- and Bandwidth-Constrained Information Routing）

把 A × B 相乘，得到一个统一形式：在每个决策点，选择视图-分辨率-抽样配置、云边分工与 chunk 长度，在延迟预算 `τ` 与字节预算 `B` 下最大化终态成功率。上一版的三层栈都是它的特例：

- **抓握确认** = 路由到「双腕 + 头 stereo」，并用 `T_oe` 恒定性读出滑移；
- **技能路由** = 云端低频选择意图（上一版 MoE 的合规形态）；
- **测试时适应** = 云端上下文估计的**低频广播**，而非每步在线更新；
- **工程层** = 预算、时序、降级与审计。

## 2. 瓶颈：把"云边 + 多视角"落成可算的量

下表把已知规格与几何推导分开标注。**【事实】** 来自官方接口与数据卡；**【推导】** 是本文按假设参数算出的量级，**待 E7xx 实测标定**；本轮不虚构实验结果。

| 观测 | 数值 / 关系 | 类型 | 对策略的含义 |
|---|---|---|---|
| 单步节拍 Δ | 33 ms（30 fps） | 事实 | 硬下限 |
| 6B VLA 推理 | ~80–105 ms | 事实（WLA 报告） | 同步必然跨 2–3 个 step |
| chunk 计算窗 | `T_a·Δ`：T_a=8→264 ms；T_a=2→66 ms | 推导 | **chunk 是云端预算**（V1） |
| 4 路 480×640 RGB | ≈3.69 MB/step（未叠帧） | 推导 | 远程带宽不可承受 |
| 头 stereo 深度精度 | `σ_z ≈ z²·σ_d/(f·b)`；z=0.5 m、f·b=24 px·m、σ_d=0.5 px → ≈5.2 mm | 推导 | 近场勉强、轴外不足（V2） |
| z=0.8 m 时同参数 | ≈13.3 mm | 推导 | 远距离必须靠腕部近场 |
| 240×320 四路 | ≈0.92 MB/step | 推导 | 4× 降，仍可再按相位裁 |
| 叠帧 `[-2,0]` | 观测字节 ≈×2 | 推导 | `obs_delta_indices` 是双刃剑 |
| teaser：step ≈ 1.337·succ + 0.09（R²=0.9955） | 两指标近共线 | teaser | 仍只优化终态成功 |
| teaser：per-task oracle − best_single = +4.26 | 技能准正交 | teaser | 云端意图路由的上界参考 |
| 最难 6 任务 | 插入 / 旋转 / 细粒度摆放 | teaser | 几何闭环的主战场 |

**可执行的三条结论**：

- **T1 计分货币唯一**：一切路由决策都以"最后一环被完成"为目标函数，不以延迟或带宽本身为荣。
- **T2 带宽是新的硬约束**：全量四路 + 叠帧在远程链路上量级不可行 ⇒ 必须"按信息量传"，而不是"能传就传"。
- **T3 延迟-精度是相位相关的**：精度相位要短 chunk（高反馈），短 chunk 又掐死云端 ⇒ 只能"云端预取意图 + 边缘闭环"，不能靠"云端加速"硬扛。
- **T4 几何可观测性是插入类失败的主因**：单视角 z 不可观测，三角化误差随 z² 增长 ⇒ **头 stereo 管全局、双腕管近场**的视图分工是必要的，不是锦上添花。

## 3. 研究问题（本轮版）

- **Q1（多视角可观测性）**：在 1 维夹爪、无触觉下，能否用头 stereo + 双腕稳定估计"物体-EE 相对 6D 位姿 `T_oe`"及其滑移，精度是否够插入 / 旋转（目标 ≤5 mm / ≤3°）？
- **Q2（信息路由最优性）**：在字节预算 `B` 与延迟预算 `τ` 下，视图 / 分辨率 / 抽样的联合选择能否在线精确求解（相机只有 4 路，配置空间小），且在同字节下不劣于固定全量配置？
- **Q3（云边意图的语义）**：云端低频"意图"该用什么量表示（子目标位姿？相对位姿增量？skill latent？），如何定义**新鲜度**并在陈旧时安全退化，避免"自信地执行过期计划"？
- **Q4（合规边界）**："云端大模型 + 边缘小控制器"在"单 checkpoint、单 API"赛制下是否仍算一个策略？若要求单机自包含，**edge-only 形态**的损失上界是多少？
- **Q5（工程真实语义）**：chunk 如何执行 / 是否插值、`action_chunk_size` 是否允许逐次变化、`image_resize` 与 `obs_delta_indices` 在何时生效、N 端口并发对带宽 / 延迟的放大——这些必须先用官方 client 复刻验证，否则一切"利用未声明语义"的优化都触碰合规红线。

## 4. 设计原则

- **P1 单一计分货币**：任何创新都要能写成"提升某任务终态成功率"的因果链。
- **P2 几何可观测量优先**：能被三角化 / 重投影验证的量才当"状态"，其余一律当带置信度的隐变量。
- **P3 预算显式化**：每个决策都消耗 `(ms, bytes)`；不允许"隐式免费"的额外视角或额外推理。
- **P4 分层而非堆叠**：云端只出低维意图，边缘保留最终执行权与安全兜底；所有跨层信息携带时间戳与新鲜度。
- **P5 合规优先**：对外仍是单 checkpoint、单 API；云边是**部署拓扑**，不是多模型提交；预备 edge-only 自包含降级形态。
- **P6 可审计**：路由决策、意图年龄、降级次数、延迟与带宽分布全部可导出，主动对齐官方的可信度口径。

## 5. 最小可提交闭环（MVP）与严格退化链

**MVP = CE-06（云边多视角代理评测）+ CE-02（多视角几何抓握 / 滑移）+ CE-03（相位自适应视角路由）+ CE-01（云边意图分层）+ 通用 VLA 基线。**

理由：CE-06 决定其余组件的边际收益排序；CE-02 / CE-03 直击几何与带宽两条硬约束、且不依赖新数据；CE-01 是最大红利但须先过 Q4 / Q5。

**严格退化链（任一环节不可用 ⇒ 行为回退而非漂移）**：

- L0 云端超时 / 掉线 ⇒ **edge-only**（缓存意图 + 本地闭环）；
- L1 多视角标定或几何失效 ⇒ 退回单腕 + EE 开环（上一版基线）；
- L2 视角路由不可用 ⇒ 固定全量低分辨率；
- L3 意图陈旧 / 与几何不一致 ⇒ 丢弃意图，边缘反射模式；
- L4 全链路失效 ⇒ **纯基线单模型提交**（永远保留一份能跑通、可信度合规的安全网）。

## 6. 预期贡献（可验收）

1. **把"云边协同"从部署口号变成可验证的截止时间预算模型**：证明 chunk 长度即云端计算预算，给出相位-分工图与 p99 可行性条件。
2. **把"多视角"从多通道拼接变成几何可观测量**：给出 `T_oe`、滑移、遮挡、标定漂移的在线估计与校准曲线（可靠性图 / 重投影残差）。
3. **提出 DBC-IR 统一形式**：视图选择 + 分辨率 + 云边分工 + chunk 长度的联合路由，给出小配置空间下的精确解与预算表。
4. **面向最难插入 / 旋转任务的 3D 相对位姿伺服闭环**，并给出它与语义 VLA 的互补条件（何时语义优、何时几何优）。
5. **一套可复现的 CloudEdgeBench**：注入延迟 / 带宽 / 云端掉线 / OOD，输出 success–latency–bandwidth 的 Pareto 前沿。

## 7. 下一轮迭代计划（深化与修剪，不推倒重来）

- **深化**：用官方 client 实测 chunk 执行语义与真实 RTT，把 V1 的预算不等式标定成查表；把多视角标定从"假设外参已知"改成"从官方数据自标定"；把 `T_oe` 的滑移判据升级为带时序的状态机。
- **修剪预案**：若 CloudEdgeBench 显示延迟 / 带宽扰动对成功率影响 <2 分，则**砍掉云边分层**，只保留多视角几何（CE-02 / CE-05）这条机制线；若多视角标定误差 >1 cm，则砍掉 CE-05，只保留 CE-02 的滑移检测。
- **保留项**：CE-06（信息价值最高）、CE-02（几何断点直击）、CE-03（带宽硬约束）。

## 8. 本轮最大风险（一句话）

**最大风险是"云边异步"把错误从执行层搬到意图层——云端基于旧观测下发的意图一旦陈旧或与多视角几何不一致，边缘会"高置信地执行一个过期计划"，而评测端对每步延迟与动作规律性的审计又会惩罚为纠错而引入的抖动，使我们在最需要闭环的插入相位反而被自己的分层卡住。**

## 0. 本轮结论摘要

**一句话路线**：把"看哪里 / 传多少 / 在哪算 / chunk 多长"统一为 **DBC-IR（受截止时间与带宽约束的信息路由）**——云端低频下发**意图**、边缘高频闭环**动作**、多视角提供**几何可观测量**，全部对齐官方延迟与可信度审计。

**三条量化依据**（前两条沿用 teaser 结构，后两条为本轮推导）：

| 依据 | 数值 | 类型 | 推出的设计 |
|---|---|---|---|
| 6B VLA 推理 vs 30 fps 节拍 | ~80–105 ms vs 33 ms/step | 事实 | 同步不可行 → chunk 即云端预算（CE-01，V1） |
| 头 stereo 深度误差 ∝ z² | z=0.5 m→≈5.2 mm；z=0.8 m→≈13.3 mm | 推导 | 头管全局、腕管近场（CE-02/05，V2） |
| 全量四路叠帧带宽 | ≈7.4 MB/step ≈ 220 MB/s | 推导 | 必须按相位选视角/分辨率（CE-03，V3） |
| teaser：step≈1.337·succ+0.09，oracle−best=+4.26 | 近共线 / 准正交 | teaser | 只优化终态成功；意图路由有上界红利 |
| 最难 6 任务 | 插入 / 旋转 / 细摆放 | teaser | 火力在 3D 相对位姿闭环（CE-05） |

**合规红线（P5）**：对外单一 checkpoint、单一 API；云边仅是部署拓扑；预备 edge-only 自包含降级；不做读题硬编码、不依赖未声明的执行语义。

| **CE-08** | AuditLayer 可审计提交层 | P2 | 延迟 / 带宽 / jerk / 降级全导出 | 接口 | 报告可导出；N 端口 ×8 h 无串扰 |

> **P0 = 本轮必做**（构成 MVP）；P1 = 视 Q1 / Q4 结果推进；P2 = 有余量再做（审计部分并入 CE-06）。

## 2. 创新点详述

### CE-01 · IntentLink 云边意图-反射分层（P0）

- **动机**：6B VLA 推理 ~80–105 ms > 33 ms/step；但接口按 chunk 交接，chunk 执行期 `T_a·Δ` 就是下一块的异步计算窗口。`T_a=8` → 264 ms，够一次云端推理；`T_a=2` → 66 ms，不够。
- **与现有方案的差异**：现有做法是"把整个策略塞进一台机器并压延迟"；我们把策略**在时间上分层**：云端只出低维意图（子目标位姿 / 相对位姿增量 / skill latent），边缘出高频动作并保留最终执行权。关键不是"云更强"，而是"云在长 chunk 相位算，边在短 chunk 相位兜"。
- **技术可行性**：中–高。意图接口极窄（≤32 维），带宽可忽略；边缘控制器可先用心跳式的相对位姿伺服 + 基线策略动作。
- **所需资源**：数据 = 官方 32 数据集；算力 = 云端 1×A100（或远程租用）、边缘推理 <10 ms；接口 = 不新增字段（意图在服务内部传递）。
- **落地步骤**：①用官方 client 复刻 chunk 语义（Q5）；②实现意图协议（时间戳 + 版本 + 场景锚点）；③边缘异步 workers 预取；④相位切换时预取下一相位意图；⑤压测 p99 与缓冲欠载。
- **风险**：①缓冲欠载（云端 p99 抖动）→ 边缘早退兜底；②意图与当前观测错位 → CE-04 门控；③合规（Q4）→ 先书面确认 + edge-only 兜底。

### CE-02 · MVGrasp 多视角几何抓握 / 滑移确认（P0）

- **动机**：无触觉、1 维夹爪，"抓住没有"是隐变量；但多视角 + 已知 EE 位姿可测**物体相对 EE 的 6D 变换 `T_oe`**。稳定抓握时 `T_oe` 恒定；打滑时漂移；空抓时物体不动而 EE 动。一个量统一三种判断。
- **与现有方案的差异**：现有做法多为"用单腕外观判成功"；我们改为**几何恒定性判据**：在抬起 / 搬运相位，比较相邻时刻的 `T_oe`，残差超阈值即滑移/空抓。
- **技术可行性**：高。官方数据有 4 路相机与 `*_ee_pose_gripper_base`；外参可先从数据/URDF 自标定。
- **所需资源**：数据 = 官方数据（含腕/头帧 + EE）；算力 = 6D 位姿估计器（单卡数小时）；接口 = 纯内部逻辑。
- **落地步骤**：①自标定各相机到 EE 的外参；②训练 / 拟合 6D 位姿头（或用现成基础模型）；③定义 `T_oe` 残差与滑移阈值；④可靠性图与阈值调优；⑤在 Unlock / Plug In Ethernet / Open Pill Bottle 专项 A/B。
- **风险**：①对称物体位姿歧义 → 用多视角 + 时序消歧；②标定漂移 → CE-07 监测；③误判不对称（漏判把可救失败变硬失败）→ 仅高置信时介入 + 重抓上限 ≤3。

### CE-03 · ActiveView 相位自适应视角 / 分辨率路由（P0）

- **动机**：四路叠帧带宽量级 ≈220 MB/s（推导），远程不可行；而不同相位的信息分布不同：接近 / 搬运看头 stereo 全局，抓握 / 对齐看双腕近场。
- **与现有方案的差异**：现有做法是固定降分辨率或固定用全部视角；我们把"传什么"变成**预算约束下的背包问题**：每个视角可选分辨率与抽样步长，在字节预算 `B` 下最大化预期成功（用相位条件的信息增益代理）。
- **技术可行性**：高。相机仅 4 路、分辨率档位极少，配置空间小，可用枚举 / 动态规划在**微秒级**精确求解（V3），无需近似。
- **所需资源**：接口 = `obs_delta_indices` + `image_resize` 声明；算力 = 极小。
- **落地步骤**：①确认 `image_resize` 与 `obs_delta_indices` 的真实生效时机（Q5）；②离线测各视角/分辨率的相位信息增益（互信息或下游成功率代理）；③在线路由（枚举）；④与固定配置在同字节下对比；⑤并发压测带宽。
- **风险**：①评测端 resize 语义与预期不符 → 先实测再定；②路由抖动引入观测不连续 → 加最小驻留时间；③过度裁剪丢失关键视角 → 保留头 stereo 低分辨率作为安全视图。

### CE-04 · StaleGuard 意图新鲜度与一致性门控（P0）

- **动机**：异步最大的危险不是"慢"，而是**过期意图被高置信执行**。桌面任务多数目标静止，但人为干扰 / 物体移动会让意图失效。
- **与现有方案的差异**：常见做法只按固定超时丢弃；我们用**场景速度自适应**的新鲜度阈值：`a_max = δ / v_obs`（V4），`v_obs` 由多视角运动估计给出；再加"意图位姿 vs 当前 `T_oe`"一致性检查。
- **技术可行性**：高（门控逻辑，几行代码 + 一个速度估计）。
- **所需资源**：接口 = 意图自带时间戳；算力 = 极小。
- **落地步骤**：①定义意图年龄与版本；②多视角估 `v_obs`；③三重门控（年龄 / 一致性 / 置信度）；④丢弃即回退边缘反射；⑤统计误执行与误杀。
- **风险**：①门控过严退化成 edge-only → 记录放弃率；②速度估计噪声 → 用保守上界；③与 CE-01 时钟同步 → 用单调时钟。

### CE-05 · Align3D 多视角 6D 相对位姿伺服（P0）

- **动机**：teaser 最难任务全是插入 / 旋转 / 细摆放，几何上都是**相对位姿对齐**问题。语义 VLA 擅长"去哪、做什么"，但不擅长毫米级闭环。
- **与现有方案的差异**：把最难相位从"整段交给 VLA"改为"VLA 选意图 + Align3D 做相对位姿伺服"：以 `T_oe` 到目标 `T*` 的误差生成动作增量，短 chunk 高频修正。
- **技术可行性**：中–高。需要可靠 6D 位姿与目标位姿定义；官方数据可提供目标位姿的统计先验。
- **所需资源**：数据 = 官方数据；算力 = 小；接口 = 无。
- **落地步骤**：①定义各任务的目标相对位姿；②误差→动作增量控制器（阻抗 / 速度级）；③插入时的接触安全（力限 / 退让）；④与 VLA 的切换准则（几何误差大用 VLA，小用伺服）。
- **风险**：①目标位姿定义错误 → 用成功 episode 反推众数；②接触后视觉遮挡 → 切到开环微动 + 监测；③伺服与评测端控制语义冲突 → 先复刻。

### CE-06 · CloudEdgeBench 云边代理评测（P0）

- **动机**：真机时段稀缺、榜单未正式发布；而云边方案必须先在**可控的延迟 / 带宽 / 掉线**下评测，否则调参是在赌网络。
- **与现有方案的差异**：常见代理评测只测策略精度；我们额外注入**通信与调度扰动**：RTT 分布、带宽上限、云端超时、N 端口并发，输出 success–latency–bandwidth 三维 Pareto。
- **技术可行性**：中–高。用官方 32 数据集做 OOD 切分（留出物体 / 背景 / 位置 / 干扰物），叠加模拟网络层。
- **所需资源**：数据 = 官方 32 份；算力 = 中；接口 = 复刻官方 client。
- **落地步骤**：①下载 / 解码管线；②OOD 切分；③网络与调度模拟器；④阶段级指标 + 终态成功率；⑤真机锚点标定相关性；⑥Pareto 报告。
- **风险**：①与真机相关性不足 → 预注册 \|r\|<0.3 即砍依赖代理的微调；②模拟网络不真实 → 用官方 client 实测 RTT 校准。

### CE-07 · CrossViewMonitor 跨视角自诊断（P1）

- **动机**：多视角的价值不只在"多看"，还在**互相校验**：重叠区的重投影残差能暴露遮挡、滑移与标定漂移。
- **与现有方案的差异**：把一致性残差当**运行时监控信号**，触发重观测 / 重标定 / 降级，而不是只当训练损失。
- **技术可行性**：高（几何计算）。
- **落地步骤 / 资源**：与 CE-02 共用管线；阈值用正常数据分布定；算力小。
- **风险**：①正常遮挡被误报 → 区分"遮挡"与"不一致"；②残差阈值随距离漂移 → 归一化。

### CE-08 · AuditLayer 可审计提交层（P2，审计并入 CE-06）

- **动机**：官方会采集延迟波动与动作统计规律性并可能据此评估可信度；在成功率接近时，可审计性是相对优势。
- **落地步骤**：延迟 / 带宽 / jerk 埋点；N 端口并发压测；动作离群限幅；产出自证报告。
- **风险**：过度平滑 / 限幅压低成功率 → 只作用残差，阈值由数据分布定。

## 3. 符号与定义（M1–M12）

| 符号 | 含义 |
|---|---|
| `π = (π_c, π_e)` | 云边策略分解：云端规划器 + 边缘控制器（对外单一服务） |
| `z` | 云端意图（子目标位姿 / 相对位姿增量 / skill latent） |
| `age_t = t − t_z` | 意图年龄（用单调时钟） |
| `v_obs` | 多视角估计的场景 / 物体运动速度 |
| `C` | 视图-分辨率-抽样配置 `{(cam_i, r_i, stride_i)}` |
| `B, τ` | 字节预算 / per-step 延迟预算 |
| `T_oe` | 物体相对 EE 的 6D 变换 |
| `ρ(C)` | 信息路由策略：相位 + 预算 → 配置 |
| `g_t` | 抓握置信度 ∈[0,1] |
| `s_t` | 滑移指示（`T_oe` 残差超阈值） |
| `T_a` | action chunk 长度（chunk = 云端计算缓冲） |
| `P_ok` | 终态成功率（唯一计分货币） |

**定义 M1（云边策略）** `π(a_{t:t+T_a} | o, ℓ) = π_e( π_c(o_{t-k:t}, ℓ) = z, o_t )`，其中云端只输出低维 `z`，边缘拥有最终动作权与安全兜底。
**定义 M2（意图新鲜度约束）** `z` 可被采用当且仅当 `age_t ≤ δ / (v_obs + ε)` 且 `d(z, T_oe) ≤ η` 且 `conf(z) ≥ κ`。
**定义 M3（路由配置）** `C = {(cam_i, r_i, stride_i)}_{i=1..4}`，字节成本 `bytes(C) = Σ_i r_i·stride_i^{-1}·c_i`。
**定义 M4（DBC-IR）** `ρ* = argmax_{C: bytes(C) ≤ B} E[P_ok | phase, C]`，满足端到端延迟 `L(C, π) ≤ τ`。
**定义 M5（几何状态）** `X_t = (T_oe,t, \dot T_oe,t, r_t)`，`r_t` 为跨视角重投影残差。
**定义 M6（滑移判据）** `s_t = 1[ ‖T_oe,t ⊖ T_oe,t−k‖ > η ]`，`⊖` 为 SE(3) 相对误差。
**定义 M7（抓握置信度）** `g_t = σ(f_θ(X_{t-k:t}))`，正样本来自"抬起后 `T_oe` 恒定"的自动标签。
**定义 M8（相位）** `z_phase ∈ {reach, grasp, lift, transport, align, insert, release, unknown}`。
**定义 M9（chunk 可行性）** `T_a ≥ ⌈(L_c^{p99} + L_e)/Δ⌉`，`Δ` 为 step 间隔。
**定义 M10（伺服律）** `a_t = K_p · log(T* ⊖ T_oe,t) + a_ff`，`log` 为 SE(3) 对数映射，`a_ff` 为 VLA 前馈。
**定义 M11（降级等级）** `ℓ ∈ {0:full, 1:edge-only, 2:single-wrist, 3:baseline}`，逐级可回退。
**定义 M12（审计向量）** `audit_t = (latency, bandwidth, jerk, age, degraded, conf)`。

```python
# ===== CE-01/03/04：云边服务（单 checkpoint、单 API）=====
class UniBotPRISM:
    def __init__(self, ckpt, tau_ms=105, byte_budget=20e6):
        self.model   = load_single_checkpoint(ckpt)     # 云端主干 + 轻专家
        self.mv      = MultiViewModel()                  # CE-02/05
        self.router  = ViewRouter(byte_budget)           # CE-03
        self.intent  = None                              # (z, t_z, conf, anchor)
        self.sessions = {}                               # 每端口隔离
        self.tau_ms, self.B = tau_ms, byte_budget

    @property
    def metadata(self):
        return {
          "control_space": "joint",
          "obs_delta_indices": self.router.declare(),    # 只声明可能用到的键/叠帧
          "image_resize": self.router.resize_table(),    # 评测端 cv2 执行
          "action_chunk_size": 8,                        # 保守固定值；变长待 Q5 验证
          "token": os.environ["UNIBOT_SUBMISSION_TOKEN"],
        }

    def reset(self, port=None):
        self.sessions.setdefault(port, Session()).reset()

    def get_action(self, obs, port=None):
        s, t0 = self.sessions[port], time.perf_counter()
        phase = s.phase_clf(obs)                          # M8
        C = self.router.choose(phase, self.B, s.bw_stat)  # M3/M4：微秒级枚举
        X = self.mv.estimate(obs, C)                      # M5：T_oe, 速度, 残差

        # CE-04：意图门控（年龄 / 一致性 / 置信度）
        z = None
        if self.intent and self._admissible(self.intent, X):
            z = self.intent.z
        else:
            s.drop_intent()                                # 回退边缘反射

        # CE-05：高精度相位优先几何伺服
        if phase in ("align", "insert") and X.ok:
            a = self.mv.servo(X, z)                        # M10
        else:
            a = self.model.edge_act(obs, z, phase)         # 边缘动作 + VLA 前馈

        # CE-02：滑移/空抓 → 保守重抓
        if self.mv.slip(X) and s.retry < 3:
            s.retry += 1
            a = self.mv.regrasp(obs, X)

        a = self.audit.clamp(a); s.last = a[-1]
        self._prefetch_intent_async(obs, phase)            # CE-01：chunk 窗口内预取
        return self.pack(a, obs)

    def _admissible(self, it, X):
        age = monotonic() - it.t_z
        vmax = X.v_obs + 1e-3
        return (age <= 0.005 / vmax) and (X.dist(it.z, X.T_oe) <= 0.01) and (it.conf >= 0.8)
```

```python
# ===== CE-03：小配置空间下的精确实例化（枚举/DP）=====
class ViewRouter:
    def choose(self, phase, B, bw_stat):
        priors = PHASE_VIEW_PRIOR[phase]           # 头 stereo 全局 / 双腕近场
        best = None
        for C in self.enumerate_configs():         # 4 路 × 少量档位 → 规模极小
            if self.bytes(C) > B: continue
            score = self.info_gain(phase, C, priors) - self.latency_pen(C)
            if best is None or score > best.score: best = (C, score)
        self.min_dwell(phase)                      # 避免路由抖动
        return best.C
```

```python
# ===== CE-02/05：多视角几何 =====
class MultiViewModel:
    def estimate(self, obs, C):
        poses = self.ho.cam_poses(obs)                 # 自标定 + 官方 EE 位姿
        X = self.backproject(obs, C, poses)            # 三角化 → 物体 6D
        res = self.reprojection_residual(X, obs, C)    # 跨视角一致性
        v = self.velocity(X, self.hist)
        return GeomState(T_oe=X, v_obs=v, residual=res, ok=(res < self.tau_r))

    def slip(self, X):  return SE3_err(X.T_oe, self.hist[-3]) > self.eta
    def servo(self, X, z):                         # M10
        T_star = z.pose if z else self.hist.target
        return self.Kp @ se3_log(T_star @ inv(X.T_oe)) + self.a_ff
```

```python
def run_episode(policy, dataset, net):
    for step, obs in dataset.stream():
```

## 5. 推导（引理 V1–V6）

**引理 V1（chunk 即计算缓冲 / 截止可行性）** 设 step 间隔 `Δ`、chunk 长度 `T_a`、云端往返+推理 `L_c`、边缘 `L_e`。评测端每执行 `T_a` 个动作后再次调用 `get_action`，故下一次响应前可用的墙钟预算为 `T_a·Δ`。若 `policy` 必须在调用返回时立即给出 chunk，则云端必须先验完成于上一 chunk 的执行期内，故可行条件为 `T_a·Δ ≥ L_c + L_e`，即 `T_a ≥ ⌈(L_c+L_e)/Δ⌉`。取 `L_c^{p99}=150 ms, L_e=6 ms, Δ=33 ms` ⇒ `T_a ≥ 5`；取 p50（90 ms）⇒ `T_a ≥ 3`。**推论**：`T_a=8` 覆盖 p99；精度相位若必须 `T_a<5`，则云端只能预取、不能同步，需 CE-04 门控。∎

**引理 V2（多视角深度 / 位姿误差传播）** 头 stereo 视差 `d = f·b/z`，故 `σ_z ≈ (z²/(f·b))·σ_d`。位姿的横向误差主要由像素量化给出，约 `σ_x ≈ (z/f)·σ_u`。取 `f=400 px, b=0.06 m, σ_d=σ_u=0.5 px`：`z=0.5 m` 时 `σ_z≈5.2 mm, σ_x≈0.6 mm`；`z=0.8 m` 时 `σ_z≈13.3 mm, σ_x≈1.0 mm`。**推论**：远距离的轴向误差已超出插入容差，必须用双腕近场（`z≲0.3 m`）补足；这正是"头管全局、腕管近场"的量化依据。∎

**引理 V3（小配置空间下路由可精确求解）** 路由变量仅为 4 路相机 × 有限分辨率档 × 有限抽样档，设每路 `m` 个配置，则总组合数 `m^4`；若以字节为状态做 DP，复杂度 `O(4·m·B)`。取 `m≤8, B` 的离散档位 ≤64，则 `m^4≤4096`，可在微秒级完全枚举，**无需近似**。若未来扩展到更多视角且目标对集合单调子模，则密度贪心仍具常数近似保证（作为可扩展性备注）。∎

**引理 V4（新鲜度门控依赖场景速度）** 若意图在 `t_z` 时刻基于观测得到，在 `t` 时刻执行，物体最大速度 `v_obs`，估计误差 `ε`，则意图导致的子目标位置误差 `≤ v_obs·(t−t_z)+ε`。要求该误差 `≤ δ` 得 `age ≤ (δ−ε)/v_obs`（式取 `ε≪δ`）。**推论**：静态场景（`v_obs≈0`）的意图可长龄使用，运动场景需极短龄 ⇒ **门控阈值必须由多视角速度估计自适应给出**，固定超时要么太松要么太紧。∎

**引理 V5（相对变换恒定性 ⇒ 滑移可检测）** 稳定抓握时物体与 EE 无相对运动，`T_oe(t)` 仅受测量噪声扰动，`‖T_oe(t)⊖T_oe(t−k)‖ ≤ η`（`η` 为噪声界）；滑移或空抓时物体与 EE 相对运动，残差超界。故 `s_t=1[残差>η]` 是一致判据；其 ROC 由 `η` 与噪声分布决定。**推论**：把"抓住 / 滑移 / 空抓"统一到同一几何量，避免三个检测器互相矛盾。∎

**引理 V6（插入容差 → 视角配置的必要条件）** 设插入间隙 `c`（如销-孔半径差），允许的最大相对位姿误差为 `c/2`。由 V2，横向误差 `(z/f)σ_u` 与轴向 `(z²/(fb))σ_d` 均需 `≤c/2`。若头 stereo 在 `z=0.5 m` 的轴向误差已 `>c/2`（例如 `c=5 mm` 时 5.2 mm 已临界），则**必须**启用腕部近场（`z≲0.3 m`）。这给出 `C` 的一个可行性约束，使路由不是纯经验。∎

## 11. 本轮最值得押注的创新点（一句话）

**押注 CE-02 + CE-05（多视角几何的抓握/滑移确认 + 6D 相对位姿伺服）：teaser 最难的任务全是插入/旋转/细摆放，它们的共同失败核是"物体相对夹爪的几何关系不可测"，而 4 路相机 + 已知 EE 位姿恰好把 `T_oe` 变成一个可三角化、可恒定性检验、可直接闭环的量——这比"再训一个更大的 VLA"更直接地打在断点上，且完全不依赖评测端的未声明语义。**

**本轮最大风险（一句话）：云边异步把错误从执行层搬到意图层——云端基于旧观测的意图一旦陈旧或与多视角几何不一致，边缘会高置信地执行过期计划，而每步延迟与动作规律性审计又会惩罚纠错抖动，使最需要闭环的插入相位反被分层卡住。**
