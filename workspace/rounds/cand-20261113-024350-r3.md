# 第 3 轮迭代（灵感循环 v3：「伦理与合规」×「评测指标」）—— 先把尺子造对，再谈把分数打高

> 承接 v2（UIP-01′~15）。本轮不加更炫的策略，而是做一次「度量审计」：**我们凭什么相信自己在真机榜单上会变好？** 两个灵感词指向同一条主线——**评测指标**问「你测的到底是什么、测得有多确定、会不会被自己骗」；**伦理与合规**问「你为了这个分数，是否越过了人、数据与规则的边界」。结论：v2 的「扰动恢复闭环」仍是对的方向，但必须被一个**可证伪的度量层**和一个**安全/合规包络**包住。

## 0. 两个直觉（先讲人话）

1. **评测指标的直觉**：如果练习卷和高考卷不是同一张，那么「把练习卷刷到满分」可能只是把偏差练得更熟练。v2 把 Gazebo 计分当作「神谕」，可它只是**结构代理**；真正决定名次的是真机上的成功率与步骤分，而且**官方如何把这两个数合成一个排名，页面并没有说清**。所以第一件事不是换策略，而是给代理分数发一张「**保真度证书**」：它只在能预测**排序**时才有资格当裁判。
2. **伦理与合规的直觉**：规则把人类写成「会撤回你进度的干扰者」，但屏幕那边是一个真人。v2 的「检测被撤回→立刻重做」在物理上可能变成**抢人手、撞人手**。真正的合规不是赛前填表，而是把「人靠近就减速/让开/停手，人离开再恢复」写进状态机。**安全不是分数的对立面；在有人参与的评价里，它本身就是分数的一部分（可信度、有效性、是否被判违规）。**

**纠偏 A（很重要）**：v2 把「单模型多任务」当成硬约束来设计。现在必须把它降级为**未核实假设**：README 的硬约束只有接口、token、端口数、每端口隔离、延迟/动作规律性；单模型/外部模型/合成数据是否允许，**只能向主办方书面确认**。这不意味着可以乱用多模型，而是意味着架构要能「**在单模型规则成立时仍合规**」，同时不为一个可能不存在的限制牺牲全部性能。

**纠偏 B**：`generalization` 里的 `unseen_object_*` / `human_*` 是**扰动实例字段**，不是完整 5 轴；每任务列出的 5 个 `episodes` 是**示例视频**，不是 5 个评测轴。位置/干扰物/背景轴仍需手册或主办方确认。v2 的「至少 11 个撤回型任务」是语义标注（可信但非官方字段），继续标注为**推断**。

**由事实直接推出的度量空白**：官方没有公开 (i) 每任务评测 episode 数 `n_t`；(ii) 成功率与步骤分的合成函数 `F`；(iii) 任务是否等权；(iv) 并列如何打破；(v) 步骤分是按 episode 平均还是取最大/最后一次。**在 `F` 未知时优化单一标量，等于赌一个没读过的评分函数。**

## 2. 两个灵感词的严格解读

### 2.1 评测指标：从「一个数」到「一个带不确定性的决策问题」

- 指标不是排行榜上的一个标量，而是**估计量**：它由有限 episode、有限任务、带噪声的真机执行得到。任何「+3%」的结论，先要问：**置信区间多宽？换一批 episode 还成立吗？换一个 `F` 还成立吗？**
- 指标必须**可证伪**：一个只能上升、不能被你主动「打崩」的指标，很可能测的是捷径而不是能力。于是引入**必要性/充分性/不变性/敏感性**四类有效性检验（§3.4）。
- 指标必须**抗 Goodhart**：代理上升而真值不升甚至下降，要有可检测的「游戏缺口」。

### 2.2 伦理与合规：三层，不要混为一谈

1. **硬接口契约（已核实）**：token 双校验、N 个连续端口且数量精确、每端口状态隔离与并发、动作形状/dtype、延迟稳定、动作统计不异常。违反＝直接拒收/低可信度，和「伦理」无关，是工程红线。
2. **赛事规则（未核实）**：是否单模型、是否允许外部预训练/闭源 API、是否允许合成数据、是否允许用评测集/示例视频训练、人工干扰的正式协议。**做法：合规问询 + 保守默认 + 可审计清单**，而不是猜。
3. **研究伦理（无论规则怎么写都成立）**：人不可以被机器人碰撞/夹伤；人类参与者数据要有来源与授权；不采集与任务无关的面部/身份信息；不伪造结果、不挑任务汇报、不隐藏负结果；合成数据要打标签、可追溯。

**关键的策略含义**：在有人干扰的任务里，**「让」（yield）不是退让，而是最优控制的一部分**——因为一次碰撞可能直接让 episode 无效、可信度受损，甚至造成伤害；而人手的干扰是有限时的，等它离开再恢复，期望损失通常小于对抗。

## 3. 核心转向：度量优先（Measurement-first）

### 3.1 官方分数的可容许模型

设任务 `t` 的评测 episode 数为 `n_t`，单 episode 成功 `y∈{0,1}`，步骤分 `s=Σ_g w_{t,g} φ_{t,g}`（满分 100）。令

```
p_t = E[y]          # 任务成功率
μ_t = E[s] / 100    # 任务步骤分（归一化）
```

若任务等权（未知），全局

```
SR   = (1/32) Σ_t p_t
Step = (1/32) Σ_t μ_t
```

官方排名＝按未知单调函数 `F(SR, Step)` 排序。定义**可容许评分族**

```
F = { F_lin(α)=α·SR+(1−α)·Step, α∈[0,1];
      F_lexSR; F_lexStep; F_min=min(SR,Step); F_harm }
```

不假设 `F`，求**最小最大后悔**：

```
π* = argmin_{π∈Π} max_{F∈F} [ max_{π'∈Π} F(π') − F(π) ]
```

若只关心排序，用秩后悔 `r_F(π)−1` 并归一化。**推论**：在 `F` 未知时，任何被支配的策略都不该选；应优先落在 Pareto 前沿的「膝点」，并显式报告它在每种 `F` 下的名次区间。

### 3.2 代理的保真度证书（不是绝对校准）

设候选策略集 `Π0`（含基线、消融、若干变体），真值向量 `J(π)=(SR,Step)`，代理 `Ĵ(π)=(ŜR,Ŝtep)`（来自 GSO/离线回放）。定义

- **秩保真度** `ρ = Spearman(rank_J(Π0), rank_Ĵ(Π0))`；
- **Top-k 重合率** `O_k = |Top_k(J) ∩ Top_k(Ĵ)| / k`；
- **选择后悔** `R_sel = rank_J(argmax_Ĵ)` 的名次减 1。

用**分层 bootstrap**（重采样任务，再在任务内重采样 episode）给 `ρ`、`O_k`、`R_sel` 置信区间。**只有当 `ρ` 的 95% 下界 > ρ0（如 0.7）且 `O_1` 在 ≥80% 重采样中一致，代理才有资格用于选型**；否则只能用于「发现结构性错误」，不能用于「宣布进步」。

### 3.3 评测预算的主动分配

总预算 `B` 个 episode 时，不要平均分。比较 A/B 时，令任务级配对差 `Δ_t=SR_{A,t}−SR_{B,t}`，方差 `σ_t²` 越大的任务越值得多测；估计绝对名次时，`p_t(1−p_t)` 越大的任务越值得多测。采用近似 Neyman/OCBA 规则：

```
n_t ∝ sqrt(σ_t² / c_t)     # c_t = 单 episode 成本
```

再取整并保证每任务 `n_t ≥ n_min`。这样能把有限的真机时段花在**最能减少排名不确定性**的任务上。

### 3.4 指标有效性：四类可证伪检验

对任何声称度量「能力 c」的指标 `m`：

- **必要性**：消融 c（遮住腕部相机、打乱语言、冻结某技能头）后，`m` 必须显著下降（`>δ_nec`）。
- **充分性**：只增强 c 的干预应使 `m` 上升（`>δ_suf`）。
- **不变性**：与 c 无关的 nuisance（光照、纹理、无关颜色、曝光）应使 `m` 变化 `<ε_inv`。
- **敏感性**：与 c 相关的扰动（未见物品、人为撤回、位置/背景）应使 `m` 变化 `>δ_sen`。
- **游戏缺口**：`G = max_{π∈Π0} [Δm_proxy(π) − Δm_true(π)]`；若 `G` 大，说明代理可被「刷」。

### 3.5 指标套件（官方两口径之外）

- **恢复类**：回归检测召回 RDR、误重做率 FRR、恢复成功率 RSR、恢复时延 TTR、步骤分追回量 clawback。
- **安全类**：人机最小距离 `d_min`、接触/碰撞率、力超限率、让行时延、对抗性动作率。
- **泛化类**：分轴通过率、**最差轴**、任务级 CVaR、泛化缺口（训练分布 vs 扰动分布）。
- **校准类**：验证器置信度的 ECE/Brier（因为 UIP-01″ 依赖阈值）。
- **实时/可信类**：延迟 p50/p95/p99、抖动 CV、动作块不连续度/统计异常率。
- **合规类**：端口数精确匹配、token 双校验通过率、每端口隔离审计、外部调用次数（若规则要求为 0）。

## 4. 瓶颈假设更新

- **H1′（最高杠杆）**：**度量不确定性比策略改进更限制名次**。在 `n_t` 小、`F` 未知、真机方差大的情况下，「选错策略」的损失可能大于「策略差一点」的损失；因此 MERIT（度量层）应排在 ACS/MSGR 之前。
- **H2′**：**`F` 的未知性可以被稳健化**：Pareto + minimax regret 能在不猜 `F` 的情况下避免最坏；反过来，只优化 SR 或只优化 Step 都可能被另一种 `F` 反超。
- **H3′**：人类干扰是**有限时、非对抗**的；安全让行的期望损失小于碰撞/违规的期望损失，且让行后恢复可追回大部分步骤分。
- **H4′**：**最差轴决定真实名次的下限**；平均值会掩盖「人扰轴/未见物品轴」的系统性失败，而这两轴恰是公开数据最缺的。
- **H5′**：**单模型是未核实假设**；架构应「默认可审计为单骨干+适配器」，但不为一个可能不存在的限制牺牲模块化收益；先问规则，再定架构。
- **H6′**：GSO 的**结构保真度 > 像素保真度**；正确用法是「排序/发现结构错误」，错误用法是「宣布绝对分数」。

## 5. 上轮清单诊断（升级 / 修剪 / 新增）

- **升级为「安全版」**：UIP-01′ → **UIP-01″**（验证器+安全门+校准）；UIP-09′ → **UIP-09″**（检测撤回，但先让行再恢复）。
- **升级为「可证」**：UIP-11 GSO → **UIP-11′**（带保真度证书的代理）；UIP-12 DRF → **UIP-12′**（带来源标签的合成数据）；UIP-02′ → **UIP-02″**（worst-axis + 稳健排序）。
- **约束/降级**：UIP-13 ACS 的「投机预计算」降级——它可能制造动作跳变/延迟异常，直接伤可信度；保留「按阶段选块长」，但加动作连续性约束。UIP-14 MSGR 加 **SCOPE 适配器预算**，避免「多模型」歧义。UIP-15 CSG 并入 **SAFE-R + MERIT**，不再单列。
- **新增（命中两词）**：**UIP-16 MERIT**（度量模型与稳健选型）、**UIP-17 SCOPE**（单模型合规包络与运行期审计）、**UIP-18 SAFE-R**（安全/伦理约束下的让行-恢复）、**UIP-19 GAP**（最差轴/CVaR 泛化画像）、**UIP-20 PROV**（数据来源、预注册与可复现台账）。
- **封存不动**：UIP-04、UIP-10 继续封存；UIP-03 已并入 UIP-14。

## 6. 本轮最值得押注

**不是某一个策略，而是「MERIT × SAFE-R」这对组合**：前者让每一次「进步」都有排序保真度与不确定性支撑；后者让「扰动恢复」从可能伤人的抢动作，变成合规、可测、可复现的让行-恢复闭环。二者都不需要新接口，却同时对准「评测指标」与「伦理与合规」两个词。

## 7. 本轮最大风险

**一句话**：MERIT 的所有「保真度证书」都只在 GSO 代理与有限候选集上成立；如果官方 `F`、评测 episode 数或真机分布与我们假设的不同，整套「稳健最优」可能只是**在错误坐标系里非常严谨**，赢下审计却输掉榜单。

## 1. 度量模型：MERIT 的形式化基础

### 1.1 分数分解（把「排名」拆成可估计的部件）

对任务 `t`，评测得到 `n_t` 个 episode：

```
y_{t,i} ∈ {0,1}                        # 成功
s_{t,i} = Σ_{g=1..G_t} w_{t,g} φ_{t,g} # 步骤分，Σ_g w_{t,g}=100
p_t = (1/n_t) Σ_i y_{t,i}
μ_t = (1/n_t) Σ_i s_{t,i} / 100
```

全局（假设任务等权，未核实）：

```
SR   = (1/32) Σ_t p_t
Step = (1/32) Σ_t μ_t
```

> 注意：失败 episode 仍可能有步骤分；因此 `SR` 与 `Step` 不是同一个量。只优化其中一个，会在另一个口径下被反超。

### 1.2 排名歧义与稳健选型

官方只写了「按平均成功率与步骤分综合排序」，没有给 `F`。取可容许族：

```
F = { F_lin(α)=α·SR+(1−α)·Step, α∈[0,1],
      F_lexSR, F_lexStep, F_min=min(SR,Step), F_harm }
```

**稳健选择**（最小最大秩后悔）：

```
for each π in Π:
    worst = 0
    for F in F:
        r = rank_F(π)              # 1 = 最好
        worst = max(worst, r - 1)
    choose π* with minimal worst
```

**Pareto 过滤**先做：若 `πa` 在 SR 与 Step 上都不劣于 `πb` 且至少一项严格更好，删除 `πb`。然后只在 Pareto 前沿上做稳健选择，避免「平均好但某一口径崩」的策略。

### 1.3 代理保真度证书（GSO 的准生证）

候选集 `Π0`（基线、消融、变体）上的真值 `J` 与代理 `Ĵ`：

```
ρ        = Spearman(rank_J(Π0), rank_Ĵ(Π0))
O_k      = |Top_k(J) ∩ Top_k(Ĵ)| / k
R_sel    = rank_J(argmax_Ĵ) − 1
```

用分层 bootstrap（先重采样任务，再在任务内重采样 episode）得到 `ρ, O_k, R_sel` 的 95% CI。**准生规则**（预先写死，避免事后解释）：

```
proxy_usable  iff  ρ_CI_low ≥ 0.70
              and  P(O_1 = 1) ≥ 0.80
              and  R_sel_CI_high ≤ 2
```

不满足时，GSO 只能用于「发现结构性错误」（例如某步谓词永远判错），**不得用于宣布策略进步**。

### 1.4 评测评分的分层 bootstrap

伪代码：

```python
def hierarchical_bootstrap(tasks, B=2000):
    # tasks: list of per-task arrays of (success, step)
    stats = []
    for b in range(B):
        t_idx = rng.choice(len(tasks), len(tasks), replace=True)
        sr_b, st_b = [], []
        for t in t_idx:
            episodes = tasks[t]
            e_idx = rng.choice(len(episodes), len(episodes), replace=True)
            sr_b.append(episodes[e_idx, 0].mean())
            st_b.append(episodes[e_idx, 1].mean() / 100)
        stats.append((mean(sr_b), mean(st_b)))
    return percentile_ci(stats, [2.5, 97.5])
```

**汇报规则**：SR、Step 各给点估计 + 95% CI；策略比较用**配对任务 bootstrap** 的差值 CI，并对任务级多重比较做 Holm 校正；不得只报最好的 5 个任务。

### 1.5 评测预算分配（真机时段很贵）

```
比较 A/B：  Δ_t = SR_{A,t} − SR_{B,t}
           n_t ∝ sqrt(Var(Δ_t) / c_t)
估计名次：  n_t ∝ sqrt(p_t(1−p_t) / c_t)
```

约束 `Σ_t n_t = B`、`n_t ≥ n_min`。先用少量 pilot episodes 估计方差，再重分配；每次真机时段结束后更新一次。目标是**最小化排名/差值的 CI 宽度**，不是最小化平均方差。

### 1.6 指标有效性审计（反 Goodhart）

把扰动家族分成 **tuning set** 与 **audit set**，audit 永不参与调参：

| 检验 | 操作 | 通过条件 |
|---|---|---|
| 必要性 | 遮腕部相机 / 打乱语言 / 冻结技能头 | 指标显著下降 `>δ_nec` |
| 充分性 | 只增强目标能力（更多该技能数据/更长训练） | 指标上升 `>δ_suf` |
| 不变性 | 改光照/纹理/无关颜色/曝光 | 变化 `<ε_inv` |
| 敏感性 | 未见物品 / 人为撤回 / 位置/背景扰动 | 变化 `>δ_sen` |
| 游戏缺口 | 在 audit set 上比较代理增益与真值增益 | `G < γ` |

**红线**：若某个代理在 audit set 上涨、真值不涨，记录为负结果并冻结该代理，而不是换一个更宽松的阈值。

## 2. UIP-16 · MERIT（Measurement-model & Evaluation-Robustness with Integrity Tests）

- **定位**：不是策略，而是**所有策略的准入层**。v3 的第一优先。
- **输入**：候选策略的离线/真机结果、任务计分点、代理 rollout、扰动轴清单。
- **输出**：
  1. `metric_report.json`：SR/Step 点估计 + CI、分轴通过率、最差轴、CVaR、恢复/安全/延迟指标；
  2. `proxy_certificate.json`：`ρ, O_k, R_sel` 及其 CI、候选集、任务子集、日期；
  3. `robust_ranking.json`：Pareto 前沿、每种 `F` 下的名次区间、minimax 选择；
  4. `audit_log.json`：必要性/充分性/不变性/敏感性/游戏缺口结果。
- **决策规则**：
  - 只有拿到 `proxy_usable=true` 的代理，才允许用其做大规模搜索；
  - 只有差值 CI 排除 0（Holm 校正后），才允许写「A 优于 B」；
  - 若候选在 Pareto 前沿上互不支配，**不强行选第一**，而是按真机预约时段做一次小规模对照。
- **与 v2 的差异**：v2 用 GSO 的绝对分数当适应度；MERIT 只用它的**排序**，并强制给出「它凭什么可信」的证书。
- **风险**：证书本身需要真机锚点；若真机时段太少，`ρ` 的 CI 会很宽，导致「不可用」——这是诚实的代价，应提前规划锚点任务。

## 3. UIP-17 · SCOPE（Single-model Compliance & OPerational Envelope）

> 前提：**「单模型」并未在 README 中写明**，是未核实规则。SCOPE 是「规则成立时稳过、规则不成立时可放宽」的**对冲设计**，不是事实断言。

### 3.1 形式定义

设推理计算图 `G_inf`，含一个预训练骨干 `B` 与一组任务/技能侧参数 `A={a_1..a_m}`（适配器、头、路由）。定义**单模型包络**：

```
(1) 基础检查点数量 = 1（不允许多个独立大模型分别服务不同任务）
(2) |θ_A| / |θ_B| ≤ ε        # 参数高效，建议 ε=5%
(3) get_action 期间无外部网络调用（无闭源 API、无在线大模型）
(4) 路由只依赖 obs（语言/图像/本体），不依赖评测端隐藏信息
(5) 所有任务共享同一视觉-语言编码器；技能侧只做低秩/小头
```

若主办方确认允许多模型/外部模型，SCOPE 通过配置开关放宽；但**默认按最严解释构建**，因为换来的是「无论规则怎么解释都能过审」的确定性。

### 3.2 运行期审计清单（与 README 硬约束对齐）

| README 约束 | SCOPE 控制 | 证据 |
|---|---|---|
| token 双校验 | 握手与每步都带 token；启动即自检 | 本地 run_client 全流程通过日志 |
| N 个连续端口、数量精确 | 启动脚本按 N 精确拉起；端口占用自检 | `ports.json` + 启动断言 |
| 每端口状态隔离 | 每端口独立 `reset()`、历史/KV/缓冲分区 | 并发压测：交错 reset 不串状态 |
| 并发不互相阻塞 | 共享后端队列 + 每请求超时 | p95/p99 压测报告 |
| 动作形状/dtype | 返回前按 schema 断言 | 单元测试覆盖每个 key |
| 延迟稳定、动作规律 | 禁止投机预计算引起的块跳变；限幅/平滑 | 延迟 CV、动作不连续度 |
| 无异常外部调用 | 运行期网络审计 | 连接日志（0 次外部） |

- **降级路径**：若 N 未知，暴露可配置的端口池，评测前按主办方 N 精确设置；绝不「多开几个碰运气」（端口数不匹配是硬拒收）。
- **与 UIP-14 的关系**：MSGR 的技能头必须落进 `A` 的预算；若技能头让 `|θ_A|/|θ_B|` 超限，优先共享低秩适配器，而不是加独立模型。

## 4. UIP-18 · SAFE-R（Safety-Aware Framework for Ethics-constrained Recovery）

### 4.1 核心思想

人类干扰不是「对手」，而是**有限时的环境事件**。策略的目标不是「抢在人类之前完成」，而是：

```
能安全预防 → 预防；人已介入 → 让行；人离开 → 核验 → 恢复 → 继续
```

**永不与人的手争抢同一空间**。这不是道德姿态，而是期望收益：一次碰撞可能导致 episode 无效、可信度受损、甚至伤害，其代价远大于让行几秒。

### 4.2 状态机

```
ACTIVE   ──(人进入安全半径 / 检测到干预前兆)──▶ PREVENT
PREVENT  ──(人继续靠近)──────────────────────▶ YIELD
YIELD    ──(人手离开安全半径持续 τ 秒)────────▶ VERIFY
VERIFY   ──(子目标未回退)────────────────────▶ RESUME
VERIFY   ──(检测到 regressed)────────────────▶ RECOVER
RECOVER  ──(恢复成功或超次数)────────────────▶ RESUME / SAFE_STOP
```

- **PREVENT**：只允许「在保持安全距离的前提下把当前子步做完」，**禁止朝人手方向加速**。
- **YIELD**：松开/保持夹爪，停止末端运动，必要时小幅后退；维持力/速度上限。
- **VERIFY**：用 UIP-01″ 的验证器比较人介入前后的子目标状态；只有确认 `regressed` 才重做，避免无谓重做。
- **RECOVER**：重做被撤回的子目标；受最大次数与时间预算约束。
- **SAFE_STOP**：超时/超次数/持续有人时，保守停在安全姿态，不冒险搏末步。

### 4.3 安全谓词与决策

```
Safe(s,a) :=  d(human, robot) > d_min
          ∧  |f_contact| < f_max
          ∧  |v_ee| < v_max   (当 d < d_warn)
          ∧  a 不指向人手方向
```

是否尝试「高风险末步」的决策：

```
attempt  iff  E[ΔStep] > λ · E[collision_risk] · C_safety + E[regression_risk] · ΔStep_prior
```

其中 `C_safety` 是安全代价（按硬约束处理可令 `λ→∞`，即只要有人靠近就不搏）。**默认采用硬约束**：`d < d_warn` 时禁止高风险末步。

### 4.4 伪代码

```python
class SAFER_Policy:
    def __init__(self, policy, verifier, d_warn, d_min, tau=0.5,
                 max_recover=2, force_max=..., vel_max=...):
        ...
    def reset(self):
        self.mode = "ACTIVE"; self.g = 0; self.recover = 0
        self.pending_regression = False

    def get_action(self, obs):
        h = self._human_state(obs)          # 距离/手部/接近速度（可用几何+检测）
        if h.dist < d_min:
            return self._yield_action(obs)          # 硬安全：先让
        if h.dist < d_warn or h.approaching:
            self.mode = "PREVENT" if self.mode == "ACTIVE" else self.mode
            act = self._safe_slow_action(obs)
            if h.dist < d_min * 1.2:
                self.mode = "YIELD"
            return act
        if self.mode == "YIELD":
            self.mode = "VERIFY"; self._verify_t = 0
        if self.mode == "VERIFY":
            self._verify_t += 1
            if self._verify_t >= tau_steps:
                st = self.verifier(obs, self.lang, self.goal(self.g))
                if st == "regressed" and self.recover < max_recover:
                    self.mode = "RECOVER"; self.recover += 1
                else:
                    self.mode = "ACTIVE"; self.recover = 0
        if self.mode == "RECOVER":
            act = self._redo_action(obs, self.g)
            if self._done(obs, self.g) or self._timeout():
                self.mode = "ACTIVE"; self.g += 1
            return act
        return self.policy.get_action(obs)          # ACTIVE
```

### 4.5 安全/伦理指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 碰撞率 | 每 episode 机器人与人的接触事件数 | **0**（硬约束） |
| 最小距离 `d_min` | episode 内人机最近距离 | 高于安全阈值 |
| 力超限率 | `|f|>f_max` 的步占比 | **0** |
| 让行时延 | 检测到人到停止运动的时间 | 越小越好，设上限 |
| 对抗性动作率 | 人手在操作区时机器人仍朝其运动 | **0** |
| 恢复成功率 RSR | 被撤回子目标最终恢复的比例 | 最大化 |
| 恢复时延 TTR | 人手离开到恢复完成的时间 | 最小化 |
| 步骤分追回 | 恢复前后步骤分差 / 被撤回分数 | 最大化 |

## 5. UIP-19 · GAP（Generalization-Axis Profiling）

### 5.1 轴的定义与可观测性

| 轴 | 符号 | 官方 `generalization` 可见? | 处理 |
|---|---|---|---|
| 未见物品 | U | 是（`unseen_object_*`） | 直接建评测子集 |
| 人为干扰 | H | 是（`human_*`） | 语义解析 + 脚本复现 |
| 位置 | P | 否 | 需手册确认；默认用物体位姿随机化近似 |
| 干扰物 | D | 否 | 需手册确认；默认加无关物体 |
| 背景 | B | 否 | 需手册确认；默认换桌面/纹理 |

### 5.2 指标

```
分轴通过率   p_{t,a} = P(success | task t, axis a)
最差轴       m_t     = min_a p_{t,a}
泛化债       GD      = (1/32) Σ_t ( p_t,avg − m_t )
任务级 CVaR  CVaR_α  = 最差 α 比例任务的平均分
```

**汇报原则**：主表同时给 `SR/Step` 均值、最差轴、CVaR；不允许只报均值。若最差轴接近 0，即使均值很高也判为「未达部署条件」。

### 5.3 压力测试矩阵（audit set 不参与调参）

| 轴 | tuning 扰动 | audit 扰动 |
|---|---|---|
| U | 公开未见物品的 70% | 预留 30% 未见物品 |
| H | 撤回时机均匀采样 | 撤回时机偏晚/偏早、连续两次 |
| P | 小范围位置抖动 | 大范围位置/朝向变化 |
| D | 单个无关物 | 多个遮挡物 |
| B | 轻微光照/纹理 | 明显背景替换 |

每个任务至少覆盖 `U/H` 两轴；`P/D/B` 待规则确认后补齐。**do-not-tune-on-audit** 写进 PROV 台账。

## 6. UIP-20 · PROV（Provenance, Pre-registration & Reproducibility）

### 6.1 数据来源标签

每条训练/评测样本带：

```json
{
  "episode_id": "T26_ep_0029",
  "source": "public | synthetic | real",
  "generator": "gazebo | drf-v1 | human-teleop",
  "license": "...",
  "human_involved": true,
  "consent": "n/a | obtained",
  "split": "train | tune | audit",
  "synthetic": false,
  "notes": "..."
}
```

- **合成数据必须可识别**：用 DRF 生成的「撤回-恢复」样本带 `synthetic=true` 与生成器版本；避免把仿真结论伪装成真机结论。
- **禁止评测泄漏**：示例视频/评测集不得进入训练；若用了公开数据集，记录版本与哈希。
- **人类数据**：只用任务相关的手部/本体信息；不采集面部/身份；若有真人示范，记录授权。

### 6.2 预注册（Pre-registration）

在真机评测前写死：

1. 假设与主指标（例如「人扰轴 clawback」为主，SR 为次）；
2. 任务子集与每任务 `n_t` 预算；
3. 分析计划（配对 bootstrap、Holm 校正、Pareto/minimax）；
4. 停止规则（达到预算即停，不因中途好看而延长）；
5. 负结果判定（代理涨、真值不涨时如何记录）。

### 6.3 复现台账

每次实验记录：代码 commit、配置、随机种子、环境版本、每任务原始结果、CI、失败 episode 列表、`metric_report.json` 与 `proxy_certificate.json`。**负结果不删除**，作为下一轮的先验。

## 10. 关键算法（补充）

### 10.1 稳健选型

```python
def robust_select(candidates, score_fns):
    # 先做 Pareto 过滤（SR, Step）
    front = pareto_front(candidates, key=lambda p: (p.sr, p.step))
    best, best_worst = None, +inf
    for p in front:
        worst = max(rank(score_fns[f], front, p) - 1 for f in score_fns)
        if worst < best_worst:
            best, best_worst = p, worst
    return best, best_worst
```

### 10.2 预算分配

```python
def allocate_budget(tasks, B, n_min, pilot_var, cost):
    w = {t: math.sqrt(max(pilot_var[t], 1e-6) / cost[t]) for t in tasks}
    s = sum(w.values())
    n = {t: max(n_min, int(round(B * w[t] / s))) for t in tasks}
    # 把四舍五入的余量补给方差最大的任务
    while sum(n.values()) < B:
        t = max(tasks, key=lambda t: pilot_var[t] / cost[t])
        n[t] += 1
    return n
```

### 10.3 安全门（与 UIP-18 一致）

```python
def safe_gate(obs, human, cfg):
    if human.dist < cfg.d_min:              return "YIELD"
    if human.dist < cfg.d_warn or human.approaching:
        return "PREVENT"
    if human.just_left(cfg.tau):            return "VERIFY"
    return "ACTIVE"
```

## 13. 本轮最大风险 & 押注

**一句话**：如果 MERIT 的保真度证书只对 Gazebo、只对少数候选、且没有足够真机锚点，那么我们会陷入「**在错误坐标系里极其严谨**」——审计全绿、榜单不动。

**→ 押注：UIP-16 MERIT × UIP-18 SAFE-R 组成的「可信度量 + 安全恢复」层**——它不承诺某个策略更强，但保证：(i) 每一次「变强」都经过排序保真度与不确定性检验；(ii) 每一次「恢复」都不会以人机碰撞为代价；(iii) 每一个结论都可追溯到数据来源与预注册分析。这正好落在「评测指标」与「伦理与合规」两个词的交点上，且完全在选手的离线算力与 API 权限之内。
