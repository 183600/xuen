# 第 13 轮 · ANCHOR-ICP：用腰部运动学替代 IMU、用双目点云配准替代深度相机，把四路 RGB 变成桌面锚定的米制场景图

> 检索/复核日期：**2026-10-29（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。研究线已到第 12 轮 CHUNK-SERVO；本轮是同一研究线的第 13 轮（本会话第 3 轮），不推倒 FACT-VLA、GEO-RESIDUAL、CHUNK-SERVO，也不与 `rounds/` 里自称第 13 轮的 SIG-MPC 候选冲突：本轮把它当作并行候选，保留其「离线实例分割标签 + 几何约束 MPC」，剪掉「在线 SAM2 + 学习世界模型」，主押注换成更底层的**米制场景状态**。

## 0. 先给结论：不是缺 IMU，是缺「米制场景状态」

三个灵感词的第一反应都很诱人，也都很危险：

| 灵感词 | 最诱人的做法 | 为什么在 UniBot 是陷阱 | 本轮的合规实现 |
|---|---|---|---|
| **惯性测量单元** | 给机器人加 IMU，或让 VLA 吃 IMU | API 不暴露 IMU；不能改硬件；官方 WLA 的 Dex1 配置根本不用 `base inertial state`；IMU 只给重力/角速度，不给物体位姿 | **KIN-IMU**：用腰关节 FK 在线重建头相机位姿，用桌面平面给重力，用腿/腰形变和 EE 跟踪误差做身体摆动/接触代理；IMU 是「概念替代」，不是「传感器伪造」 |
| **场景理解** | 在线跑 SAM2 / GroundingDINO / 3D 场景图大模型 | 单模型规则；每端口多一份 GPU；远程 RTT 下延迟不可控；API 没有 depth | **TABLE-SCENE**：双目点云 + 桌面 RANSAC + URDF 自遮挡剔除 + 聚类/OBB + 语言/任务角色绑定，输出桌面锚定的低维场景图；离线 SAM2 只做标签/增强 |
| **点云配准** | 把原始点云/深度喂给 VLA，或训一个 3D 世界模型 | StereoPolicy 已指出点云在透明/反光/细结构上脆弱；WLA 基座是 RGB-only；在线大模型违规 | **ICP-TARGET + EDIT-ICP**：演示关键帧点云配准给目标/受器相对位姿；episode 地图配准残差做人为干扰检测；配准只做测量层，不替代策略 |

我的判断是：榜首不到 30%（预览榜），所有模型共享的瓶颈不是「语义不够强」，也不是「IMU 没接上」，而是——

1. **API 没有米制场景状态**。四路 RGB + 本体 + 语言，没有 depth、camera_info、force/torque、IMU。VLA 可以认出「杯子」，但不知道杯子在桌面坐标系里离夹爪多少毫米、桌面法向是什么、杯架口朝哪。
2. **官方 WLA Dex1 基线实际上是「单目 + 腕部」**。`unitree_img_wo_stereo` 只用 `head_stereo_left` + 两路腕部，**右头双目图被丢弃**；`unitree_base` 的 state keys 只有左右 EE、grippers、waist、左右腿，不用 `state_d435`/`state_torso`/`base_rot`。也就是说，官方基线既没有用右眼，也没有用头相机位姿。
3. **数据里其实有足够的信息重建米制状态**。32 个挑战数据集全部有 `state_torso`、`state_d435`、`waist_state_joint`；头双目已标定（fx≈282.37 px、基线≈58.25 mm）；`state_torso` 的 rpy 就是腰关节的 `[roll, pitch, yaw]`，`state_d435` 相对 `state_torso` 是固定安装变换。**在线只要 `lower_body[-3:]` + 两个固定变换，就能重建头相机位姿**——这是不依赖 IMU 的「虚拟 IMU」。
4. **右头双目是白送的深度**。StereoPolicy 已经证明双目比 RGB/Depth/点云更稳；我们不需要把双目特征塞进 VLA，只需要用它算桌面平面、物体簇、目标/受器位姿和人为干扰残差。点云脆弱没关系，因为几何层有桌面先验、模板配准、置信度门控和 RGB 回退。

所以本轮押注叫 **ANCHOR-ICP**：

> **用腰部关节运动学重建头相机位姿（替代 IMU/外参），用桌面平面给出重力，用双目点云配准给出目标/受器的米制位姿和人为干扰残差，把四路 RGB 变成桌面锚定的场景图；WLA 仍是唯一学习模型负责语义与动作，确定性几何层负责最后 3 厘米、外观泛化和人为干扰。**

一句话：**把「没有 IMU、没有深度」的 API，变成「有米制场景状态」的系统；不是再加一个模型，而是补上 VLA 缺的那层几何。**

## 1. 本轮新核实/新推导的事实（只列会改变方案的）

### 1.1 榜单仍是预览，但「榜首不到 30%」的难度信号成立

2026-10-29 复核：

- 排行榜页 <https://unibot.unitree.com/leaderboard.html> 显示「即将发布 Coming Soon」，表格为空。
- `leaderboard_data.json` 仍返回 8 个模型、32 个任务、`generated_from: "gen_leaderboard.py"`；8 个模型仍是 MolmoAct2 29.7 / WALL-OSS-0.5 28.5 / DreamZero 27.9 / Spirit-v1.5 25.9 / DM0 23.5 / PI-0.5 22.8 / GigaBrain-0 22.6 / GR00T N1.5 20.5。
- 详情页视频是「测试视频占位」；runs 页成功率出现 25.1%、32.7%、38.2% 这类非 10% 整数倍，说明不是 32×10 的正式评测。
- 前几轮已做 `step ~ success` 回归：每个模型 R² ≥ 0.9999996；241 个唯一成功率里 217 个不是 10% 的整数倍；跨模型任务级相关均值 0.098。

**结论**：29.7% 只能当「赛事方把上限压得很低」的难度信号，不能当实测 SOTA；也不能从任务排名里挖「哪个任务难」。但「所有模型都不到 30%」这件事，足以支持「共享执行/几何瓶颈」的判断。

### 1.2 API 没有 IMU/depth，但给了四路 RGB；右头双目是官方基线未用的资产

2026-10-29 复核 `unitreerobotics/unibot_submission` 的 README 与 `example/example_env.py`：

- 观测：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB 480×640；`left_arm/right_arm [7]`、`left/right_ee_pose_gripper_base [6]`、`left/right_gripper [1]`、`lower_body [15]`、`language str`。
- **没有** depth、camera_info、force/torque、tactile、IMU。
- 动作：`control_space` 仅 `"joint"` 或 `"ee"` 互斥；`action_chunk_size` 在握手期声明一次，所有 `get_action` 的 leading time-axis 等长；evaluator 执行完整个 chunk 才再次调用；chunk 内无新观测、无打断。
- 多机器人：从 8765 起暴露 N 个连续端口，N 必须等于机器人数量；每端口独立、`reset()` 状态隔离。

**关键推论**：右头双目是 API 白送的，官方 WLA Dex1 配置却只用左头。我们不需要为了用右眼去改 VLA 的输入层；先把右眼用于几何层，是成本最低的差异化。

### 1.3 数据里没有 IMU，但有可重建头相机位姿的腰关节 + 头相机位姿标签

2026-10-29 逐一读取 32 个挑战数据集 `meta/info.json`：

- 合计 **33,276 episodes / 18,282,246 frames / 169.28 h / 30 fps**；单任务 969–1,533 集。
- 全部有 `state_torso [6]`、`state_d435 [6]`、`waist_state_joint [3]`；**全部没有** `state_base_rot`/IMU 字段。
- `state_torso` 名称是 `x,y,z,roll,pitch,yaw`；`state_d435` 也是 `x,y,z,roll,pitch,yaw`；`waist_state_joint` 是 `yaw,roll,pitch`；`lower_body [15]` = 12 腿关节 + `waist_yaw, waist_roll, waist_pitch`。

我在 HangCup 的 42 行样本上做了数值核对（纯 Python，无 numpy）：

- `state_torso.rpy` 与 `[waist_roll, waist_pitch, waist_yaw]` 的误差 < 1e-3 rad；`state_torso.xyz` 在该样本中恒为 `[-0.004, 0, 0.044] m`。
- `T_torso_d435 = inv(T_base_torso) * T_base_d435` 的平移为 `[0.0576235, 0.0175300, 0.4298700] m`，42 行内变化 < 1e-6 m；旋转也恒定。
- 也就是说：**`state_d435` = `state_torso` × 固定安装变换；`state_torso` = 固定平移 + 腰关节 rpy。在线只要 `lower_body[-3:]`，就能重建头相机位姿。**

这不是「数据里没有 IMU 所以做不了」，而是「数据里给了比 IMU 更有用的头相机位姿标签，只是官方基线没用」。G0 要在 32 个数据集、多台机器人上复核这个固定变换是否一致；不一致就每台机器人标定一次。

### 1.4 头双目标定与深度误差：0.3–0.5 m 够场景图，最后 1–2 mm 靠腕部/模板

HangCup `camera_params`：

- 头双目 `fx≈282.37/281.87 px`，`fy≈282.75/282.32 px`，`cx≈311.53/329.96 px`，`cy≈256.63/249.51 px`；基线 `T=[-58.2526, -0.1675, 0.5786] mm`，`rectified: true`。
- 注意：左右 `cx` 差 18.4 px、`cy` 差 7.1 px，**不能默认两张图已经严格行对齐**；G0 要用提供的 K/R/T 做 Bouguet 校正或验证对极误差 ≤1 px，再算视差。
- 腕部 color 相机**有内参**：左 `fx=436.41, fy=435.92, cx=323.92, cy=242.93`；右 `fx=435.12, fy=434.50, cx=319.02, cy=240.99`；含 inverse Brown-Conrady 畸变。第 12 轮说「腕部无内参」需要更正。
- 头双目深度误差（`∂Z/∂d = -Z²/(f b)`，`f≈282.37`，`b=0.0582526 m`）：

| 工作距离 Z | 1 px 视差误差 → 深度误差 | 0.1 px 亚像素 → 深度误差 |
|---:|---:|---:|
| 0.3 m | 5.5 mm | 0.55 mm |
| 0.5 m | 15.2 mm | 1.52 mm |
| 0.8 m | 38.9 mm | 3.89 mm |
| 1.0 m | 60.6 mm | 6.06 mm |

**含义**：头双目在 0.3–0.5 m 的接近段足够做桌面平面、物体簇、目标/受器粗位姿和障碍物；**不能把 1 px 当成毫米级**。最后 1–2 mm 的插入/挂/拉链对齐，必须靠腕部近距图像（10–20 cm）、已知物体几何或演示模板配准，不能只靠头双目。第 12 轮说「头双目足够毫米级」过于乐观，本轮修正。

### 1.5 官方 WLA Dex1 配置不使用 base inertial state；缺的不是 IMU 输入，是米制场景状态

2026-10-29 复核 `unifolm-wla`：

- 6B 参数，约 2,500 h 真机数据，64 任务；`chunk_size: 30` @ 30 fps；`action_dim: 54`；冻结 `qwen_vl_interface`，只训 DiT action head + robot-state projector；默认单张 24 GB GPU 可微调。
- 60 维 state 布局里确实有 `[41:47]` **base inertial state**：body 系重力方向 + 归一化三轴角速度。
- 但 Dex1 的 `unitree_base` state keys 只有：`left_ee_pose`、`right_ee_pose`、`left_gripper`、`right_gripper`、`waist_joint`、`left_leg`、`right_leg`；**没有** `state_d435`、`state_torso`、`base_rot`，也没有 base inertial state。
- 图像配置 `unitree_img_wo_stereo` 只用 `head_stereo_left` + `wrist_left` + `wrist_right`；**右头双目未用**。

**结论**：官方基线不是「因为 API 缺 IMU 所以不能用 IMU」，而是「Dex1 配置根本不接 base inertial state」。即使我们能估出重力/角速度，把它塞进 VLA 也只解决「身体姿态」，不解决「物体在哪」。所以本轮不把 IMU 当 VLA 输入，而把它当几何层的重力/自运动先验；真正的缺口是**桌面锚定的物体/受器米制状态**。

### 1.6 规则：60% 外观泛化 + 40% 位置/人为；单模型；N 端口

2026-10-29 通过 `r.jina.ai` 复核官方参赛手册（中文版）：

- 32 任务，每任务 10 次独立运行；5 类泛化各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
- 单次真机上限 180 s；排名先总平均成功率，再总平均步骤分，再更早提交。
- 所有任务须基于同一模型完成，不得混合多个模型一起测试；模型类型不限。
- 跨 N 台机器人，从 8765 起暴露 N 个连续端口；每端口独立、`reset()` 状态隔离；有不计分的单任务测试通道。
- `observation.language` 在 episode 内固定。

**关键算术**（假设 5 类互斥，手册「各出现 2 次」支持这个假设）：

- 干扰物 + 背景 + 未见物品 = **6/10 = 60%** 试次直接考验「外观变了，目标实例还是不是它」。
- 位置 + 人为干扰 = **4/10 = 40%** 试次直接考验「目标动了/被人动了，能不能重新定位并恢复」。
- 接触精度（插入/挂/叠/拉链/锁）贯穿所有轴，但集中体现在刚性物体任务。

几何层对这两组轴的价值不同：桌面锚定 + 演示配准主要吃 60% 外观泛化；EDIT-ICP 主要吃 20% 人为干扰；位置泛化两者都吃。这个映射决定了本轮的实验优先级。

### 1.7 相关前沿：双目有用但点云脆弱；3D 场景图有价值但太重；本体感觉会主导

2026-10-29 检索到的、会改变方案的证据：

- **StereoPolicy**（arXiv 2605.09989）：双目输入优于 RGB、RGB-D、点云；但点云在透明/反光/细结构上脆弱。→ 我们用双目算几何，但不把原始点云喂给 VLA；几何层只输出低维场景状态和约束。
- **PointWorld**（arXiv 2601.03782）、**ChronoGraph**（arXiv 2609.39665）：RGB-D 点云世界模型/4D 功能场景图有价值，但需要 depth、模型重、在线推理贵。→ 我们做轻量确定性桌面场景图，不做世界模型。
- **When would Vision-Proprioception Policies Fail?**（ICLR 2026，arXiv 2602.12032）：本体感觉会主导，视觉在需要目标定位的过渡段作用有限。→ 支持「显式目标定位」的必要性；KIN-IMU 只做自运动/重力，不替代视觉目标定位。
- **Targeted Modality Dropout**（arXiv 2610.09566）、**WLA³**（arXiv 2609.15870）：模态 dropout 能提升间歇视觉缺失下的鲁棒性。→ GEO-TOKEN 训练时做几何模态 dropout，测试时按置信度门控。
- **Object-Centric Residual RL**（CoRL 2026）：以物体中心状态 + 本体感觉 + 基座 VLA 动作做残差，可零样本迁移。→ 证明「物体中心状态」有价值；但它是第二个学习策略，可能违反单模型规则，我们只借表示，不借第二个策略。
- **Blind Dexterity**（arXiv 2608.29487）：G1 纯本体感觉可做部分灵巧操作，但不用 IMU 反馈。→ 本体感觉有价值，但不能替代目标定位；KIN-IMU 是几何先验，不是盲操作。
- **TemporalFlow-VLA**（arXiv 2608.26821）：几何监督只在训练期用，部署不跑几何路径。→ 我们的「离线特权几何 + 在线重建」是同一思路，但把几何保留在部署期做测量和约束。

## 2. 诊断：榜首方法的共同瓶颈

把 8 个模型按公开路线粗分（B 级证据，未逐一复现）：

| 模型 | 公开路线（粗分） | 强项 | 共享瓶颈 |
|---|---|---|---|
| MolmoAct2 29.7% | 空间推理/动作推理 VLA | 语义、空间指代 | 无 depth/force；chunk 开环；无米制场景状态 |
| WALL-OSS-0.5 28.5% | 开源具身基座 VLA | 数据规模、通用性 | 同上 |
| DreamZero 27.9% | 视频/世界模型（14B 级） | 未来预测、场景想象 | 视频预测不等于毫米级几何；推理重 |
| Spirit-v1.5 25.9% | VLA | 语义泛化 | 同上 |
| DM0 23.5% | 扩散策略/VLA | 多模态动作 | 同上 |
| PI-0.5 22.8% | 通才 VLA | 语义泛化、跨任务 | 无 depth/force；开环 chunk |
| GigaBrain-0 22.6% | VLA | 数据/任务覆盖 | 同上 |
| GR00T N1.5 20.5% | 人形基座模型 | 仿真/数据引擎 | sim-to-real、接触精度 |

共同点不是「模型不够大」，而是：

1. **输入缺米制几何**：RGB 能给语义，给不了「桌面坐标系下的目标位姿/受器朝向/自由空间」。
2. **执行缺闭环**：30 步 chunk 在接触段是开环；第 12 轮已把这一点拆成 CHUNK-SERVO。
3. **泛化缺显式结构**：外观/背景/干扰物变化时，端到端模型只能靠数据先验；没有「桌面锚定」这种不变结构。
4. **人为干扰缺检测**：20% 试次会在执行中改场景；纯 RGB 差分受光照/背景影响，纯 VLA 没有「场景变了」的显式信号。

ANCHOR-ICP 对这四点的回答是：用 KIN-IMU 补自运动/重力，用 TABLE-SCENE 补米制结构，用 ICP-TARGET 补目标/受器位姿，用 EDIT-ICP 补人为干扰，用 CHUNK-SERVO 补闭环。**全部是确定性几何/控制，不新增学习模型。**

## 3. 方法：ANCHOR-ICP

### 3.1 总览：几何层（确定性，CPU）+ VLA（唯一学习模型）+ 伺服（CHUNK-SERVO）

```
四路 RGB ──┬─ 左头 + 腕部 ───────────────→ WLA（6B，唯一学习模型）──→ 30 步语义规划
           │                                                        │
           └─ 左右头 ─→ 双目校正 ─→ 点云 ─→ TABLE-SCENE ──┐        │
                                                          ├→ 目标/受器位姿、约束
 waist/leg/EE ─→ KIN-IMU ─→ 头相机位姿 ─→ 桌面系 ─────────┘        │
                                                          ├→ EDIT-ICP ─→ 人为干扰信号
                                                          └→ GEO-TOKEN（可选）──→ action expert
                                                                   │
                                             CHUNK-SERVO（5 步约束 QP）←── 目标/约束
                                                                   │
                                                                   └→ 关节/EE 动作
```

- **WLA 仍是唯一学习模型**；几何层没有学习权重（离线 SAM2 只做标签/增强，不部署）。
- **几何层是测量层**：输出场景图、目标位姿、约束、编辑分数；不直接输出动作。
- **CHUNK-SERVO 是控制层**：每 5 步重规划一次，块内仍开环；几何层在每个 chunk 边界更新。
- **GEO-TOKEN 是可选第二级**：把场景图压成低维 token，注入同一 WLA checkpoint 的 action expert；不做也可以先用「几何层 + 伺服」拿到大部分收益。

### 3.2 KIN-IMU：用腰关节 FK 替代 IMU/头相机外参

#### 3.2.1 头相机位姿重建

离线标定（用数据集里的 `state_torso`/`state_d435`）：

```math
T_{torso,d435} = \left(T_{base,torso}\right)^{-1} T_{base,d435}
```

在 HangCup 42 行样本上，`T_torso_d435` 的平移恒为 `[0.0576235, 0.0175300, 0.4298700] m`；旋转也恒定。G0 在 32 个数据集上复核，若某台机器人不一致，就用该机器人的一小段数据重标定。

在线重建（API 只给 `lower_body[-3:]`）：

```math
T_{base,torso}(t) = \mathrm{Trans}([-0.004,0,0.044]) \cdot R_z(\mathrm{waist\_yaw}) R_y(\mathrm{waist\_pitch}) R_x(\mathrm{waist\_roll})
```

```math
T_{base,d435}(t) = T_{base,torso}(t) \cdot T_{torso,d435}
```

注意：上面的 rpy 顺序/符号要用 G1 URDF 和数据集复核；HangCup 样本里 `state_torso.rpy = [waist_roll, waist_pitch, waist_yaw]`，误差 <1e-3 rad。`state_d435` 是 D435 机体坐标，不是左目光学坐标；到左目光学系还要乘一个固定 `T_d435,left_optical`（从 URDF/标定来），G0 用桌面平面/重投影验证。

#### 3.2.2 桌面重力/基座倾角

桌面平面在头相机系下的法向 `n_c`，变换到 base 系：

```math
n_b = R_{base,d435}(t) \cdot R_{d435,c} \cdot n_c
```

若桌面水平，`n_b` 就是 base 系下的「上」方向；它与 base z 轴的夹角给出基座 roll/pitch 的估计：

```math
\theta_{tilt} = \arccos\left(\frac{n_b \cdot e_z}{\|n_b\|}\right)
```

这就是「虚拟 IMU」的重力分量。它不替代真实 IMU 的线加速度，但对桌面任务足够：重力只用来校正桌面平面、判断基座是否倾斜、给场景图一个稳定的 z 轴。若任务表面不是水平（传送带、斜面、架子），不要把它当重力；用机器人标称直立姿态或腿/腰运动学兜底，并在场景图里标记 `gravity_confidence`。

#### 3.2.3 身体摆动/接触代理

API 没有力/触觉，但有三样东西：

- 腿/腰关节相对标称站姿的偏差 `Δq_leg/waist`；
- 腰关节速度（由相邻 chunk 的 `lower_body[-3:]` 差分）；
- EE 跟踪误差 `e_ee = q_ee^{cmd} - q_ee^{state}`（`action` 与 `observation` 都有 EE pose）。

把这三样合成一个低维「身体摆动/接触代理」：

```math
s_{body} = [\Delta q_{leg}, \Delta q_{waist}, \dot{q}_{waist}, e_{ee}, \|e_{ee}\|]
```

它不是 IMU 的角速度，但它能在接触/碰撞/被人推时给出异常信号；用于：
- 伺服增益调度（接触段降速/降增益）；
- EDIT-ICP 的「机器人自运动」解释变量（避免把机器人自身运动误判为场景编辑）；
- 失败恢复（跟踪误差大 → 暂停/重观测）。

#### 3.2.4 角速度/视觉里程计（可选）

若需要角速度，可以用相邻 chunk 的 `T_base,d435` 差分，或用双目视觉里程计（VO）估计相机运动。桌面任务基座基本静止，角速度接近零；这一项是可选，不作为主路径。**不要声称 KIN-IMU 等于真实 IMU**：它只给重力方向、头相机位姿、身体摆动代理；线加速度/高带宽角速度没有。

### 3.3 TABLE-SCENE：桌面锚定的米制场景图

#### 3.3.1 双目深度

- 输入：`cam_left_high`、`cam_right_high` 480×640。
- G0：用 `camera_params.head_stereo` 的 K/R/T 做 Bouguet 校正（或验证已校正），检查对极误差 ≤1 px；不要假设左右 `cx/cy` 相同。
- 在线：SGBM/BM + 亚像素 + 左右一致性检查 + 小孔填充；只保留 ROI（桌面 + 机械臂前方）内的点；下采样到 2–5 cm 体素。
- 失败模式：纹理弱、透明、反光、细结构 → 深度稀疏/错误。**不要求稠密深度**；桌面平面、物体簇、模板配准都能在稀疏点上工作；置信度低就回退。

#### 3.3.2 桌面平面

- 在 ROI 内 RANSAC 平面拟合；用 `n_b` 与 base z 轴的夹角、平面内点比例、平面高度范围（0.6–1.0 m）选主平面。
- 建立桌面坐标系 `T_table,base`：原点取桌面中心或机器人 base 在桌面的投影；z 轴沿桌面法向；x 轴取机器人前方在桌面的投影。
- 桌面系是场景图的锚：位置/背景/基座小漂移都被归一化；物体/受器都用桌面系坐标。

#### 3.3.3 机器人自遮挡剔除

- 用 G1 URDF + 观测到的 `left_arm/right_arm/lower_body` + gripper 状态，渲染机器人本体到左头相机；膨胀 2–3 px；剔除落在 mask 内的点。
- 头部/躯干也会遮挡：用 `T_base,d435` 和 URDF 的相机安装变换渲染整个上半身。
- mask 不完美时用 trimmed ICP（只取内点）和深度一致性检查；不要假设分割完美。

#### 3.3.4 聚类与 OBB

- 去平面、去机器人后的点做欧氏聚类（半径 1.5–2.5 cm，最小簇 50 点）。
- 每簇算 centroid、PCA/OBB（center、extent、yaw）、颜色直方图、点数、平均深度、置信度。
- 对桌面上的薄片/细长物体（网线、拉链、试管）降低 `min_cluster_size`，并用腕部 2D 检测补；不要强求每个物体都有完整点云。

#### 3.3.5 角色绑定

- 离线：每个任务有固定的语言指令/任务 ID；建立「任务 → 目标类别/受器类别/关键属性」的模式表（确定性关键词 + 同义词）。
- 在线：用语言/任务模式给簇打角色：`target`、`receptacle`、`distractor`、`obstacle`、`unknown`；用演示模板（3.4）给目标/受器做实例级匹配。
- 未见物品：模式表只能给类别，实例匹配会低置信；此时角色退化为「语言指向的类别 + 几何上最可能的簇」，并让 VLA 主导；几何层只提供位姿/避障，不强行绑定。
- 干扰物：多出来的簇标为 `distractor/obstacle`；不进入目标位姿，但进入伺服避障约束。

#### 3.3.6 场景图 schema

### 3.4 ICP-TARGET：用演示点云配准给目标/受器相对位姿

这是第 12 轮 DG-KEYFRAME 的 3D 升级：不再检索 2D 目标图，而是检索演示关键帧的**桌面系点云**，配准到在线点云，转移相对 EE 位姿。

#### 3.4.1 离线关键帧

- 对每个任务、每个演示，选接触前/释放前的关键帧（用 EE 速度、夹爪开合、接触代理、任务阶段自动选；也可用第 10 轮 FACT-VLA 的阶段标签）。
- 用数据集里的 `state_d435`（精确头相机位姿）+ `camera_params` 把关键帧 RGB-D（双目算深度）转到桌面系；存目标簇/受器簇的点云、OBB、颜色、相对 EE 位姿。
- 每个任务存 20–100 个模板；按物体类别/受器类别/阶段聚类；模板库大小控制在每任务 <50 MB。

#### 3.4.2 在线配准

1. 在线点云转到桌面系（用 KIN-IMU 的 `T_base,d435` + 桌面系）。
2. 目标/受器簇与模板做全局配准：FPFH + RANSAC（或 RANSAC + 点到面 ICP），再用 trimmed ICP 精配。
3. 输出 `T_table_obj`/`T_table_rec`、fitness、RMSE、inlier ratio。
4. 用 `T_table_obj` 把模板里的相对 EE 位姿转成在线目标：
   `T_base_ee* = T_base_table * T_table_obj * T_obj_ee_demo`。
5. 若目标被遮挡/点云太少，退化为「桌面系 + 2D 腕部检测 + VLA 的 EE 动作」；不要强行配准。

#### 3.4.3 置信度与回退

- `fitness ≥ 0.6` 且 `RMSE ≤ 1.5 cm`：接受几何目标；
- `0.4–0.6`：只用于避障/约束，不用于目标位姿；
- `< 0.4`：几何层降级为「桌面平面 + 机器人 mask + 障碍物」，目标位姿交给 VLA/腕部。
- 每个任务在 G1 上标定阈值；阈值不是全局常数。

#### 3.4.4 为什么比 2D 检索强

- 2D 检索对视角/背景/遮挡敏感；3D 模板在桌面系里对位置/背景变化不变。
- 2D 只能给「像不像」，3D 配准给「差多少毫米/多少度」，可直接进伺服 QP。
- 3D 配准的 fitness/RMSE 是天然的置信度，可门控；2D 相似度没有几何意义。

### 3.5 EDIT-ICP：用配准残差检测人为干扰

#### 3.5.1 episode 地图

- episode 开始/第一个 chunk：用 TABLE-SCENE 建初始地图 `M_0`（桌面系点云 + 物体簇 + 角色）。
- 每个 chunk 边界：把当前点云配准到 `M`（桌面系已知，ICP 只做小修正）；更新地图（滑动平均/置信度）。
- 地图只保留桌面 ROI + 物体簇，不建稠密 SLAM；内存可控。

#### 3.5.2 残差

```math
r(x) = \left\| \mathrm{ICP}(P_t, M) - M \right\|
```

在配准后，剔除：
- 机器人本体（URDF mask）；
- 已被夹爪抓取的物体（用 EE pose + gripper 状态 + 模板）；
- 预期运动（VLA 计划/EE 轨迹附近的点）。

剩下的残差簇如果：
- 在目标/受器附近；
- 连续 2 个 chunk 出现；
- 位移 > 3 cm 或点数 > 阈值；

就判为 `edit`，输出 `edit_score`、区域 centroid、类型（move/add/remove）。

#### 3.5.3 检测后的动作

- 暂停当前 chunk 的后续步骤（如果 API 允许在 chunk 边界停；chunk 内不能打断，所以最快是下一个 chunk 边界）；
- 重新跑 TABLE-SCENE/ICP-TARGET，更新目标位姿；
- 让 WLA 重新规划，或让伺服追新目标；
- 如果目标被拿走/不可恢复，进入安全回撤/重观测，不要盲抓。

**边界**：chunk 内没有新观测，EDIT-ICP 最快只能在下一个 chunk 边界生效；这不是 30 Hz 的干扰响应，而是「每个 chunk 一次」的检测。第 12 轮已经修正过「5 步伺服不是 30 Hz 闭环」，这里同样要诚实：**EDIT-ICP 的延迟是 `H_c/f_c + τ`，H_c=5 时约 167 ms + RTT。**

### 3.6 GEO-TOKEN：把场景图压成低维 token，注入同一 WLA

这是可选的第二级；第一级「几何层 + 伺服」不依赖它。

#### 3.6.1 token schema

| 组 | 维度 | 内容 |
|---|---:|---|
| table | 4 | 桌面法向 3 + 偏移 1 |
| gravity/body | 3 | base tilt roll/pitch + confidence |
| target | 10 | centroid 3 + extent 3 + yaw 1 + confidence 1 + fitness 1 + rmse 1 |
| receptacle | 10 | pose 6 + aperture 2 + confidence 1 + fitness 1 |
| distractors/obstacles | 6K | K=4：centroid 3 + extent 3 |
| body proxy | 8 | waist 3 + leg deviation 2 + EE error 2 + contact 1 |
| edit | 4 | edit score 1 + region centroid 3 |
| **合计** | **63** | K=4 |

#### 3.6.2 adapter

- 63 维 → LayerNorm → MLP（63→256→token_dim）→ 1–4 个 geometry tokens。
- 与 WLA 的 state tokens 拼接或 cross-attend；只训 adapter + action head，VLM/DiT 主干冻结（沿用官方微调配方）。
- 若 WLA 代码不方便加 token，第一级先不做；不要为了 token 改坏基线。

#### 3.6.3 模态 dropout

- 训练时：以 p=0.2 随机把整个 geometry token 块置零；以 p=0.1 随机置零单个组（target/receptacle/edit/body）。
- 测试时：按置信度门控——`fitness < 0.4` 或 `depth_conf < 0.3` 时置零对应组；不要喂垃圾几何。
- 这样策略不会过度依赖几何；几何失败时退化为 RGB-only WLA，而不是崩溃。

#### 3.6.4 离线特权几何 vs 在线重建

- 离线：用数据集里的 `state_d435`/`state_torso` 精确位姿算 token（特权信息）。
- 在线：用 KIN-IMU 重建的头相机位姿算 token。
- 训练时随机混用「精确位姿」和「重建位姿 + 标定噪声」；让 adapter 见过在线误差，避免离线/在线分布差距。这是合法的特权信息使用：测试时不用 `state_d435` 标签。

### 3.7 CHUNK-SERVO 约束：把几何变成 QP 约束

第 12 轮的伺服只看误差；本轮把场景图变成约束：

- **桌面约束**：EE/夹爪不得低于桌面 + 安全余量（除非任务要求接触）；
- **障碍约束**：distractor/obstacle 的 OBB 膨胀后作为禁入区；
- **关节限位/速度限幅**：来自 URDF 和当前 `lower_body`；
- **视野约束**：目标/受器保持在头/腕相机视野内（避免追丢）；
- **夹爪开口**：目标 OBB 宽度 vs 夹爪开口，决定抓取姿态；
- **接触段**：法向速度降幅、增益降、最大步长降。

QP 形式（每 5 步重规划一次）：

```math
\min_{u_{0:H-1}} \sum_{k=0}^{H-1} \|x_k - x_k^{target}\|_Q^2 + \|u_k\|_R^2
```

```math
\text{s.t. } x_{k+1} = f(x_k, u_k) \text{ (运动学)};\quad
g(x_k, u_k) \le 0 \text{ (桌面/障碍/限位/视野)}
```

`H=5`，`f` 用简单运动学/EE 积分，不用学习动力学；求解 10–15 步 QP，CPU 毫秒级。块内仍开环，但每个块都在约束内。

### 3.8 为什么合规

- 几何层没有学习权重；SGBM/RANSAC/ICP/QP 都是确定性算法，不是「第二个模型」。
- GEO-TOKEN 是同一 WLA checkpoint 的 adapter；不引入第二个策略网络。
- 离线 SAM2/GroundingDINO 只用于生成标签/增强，不部署；若赛事方追问，明确「训练期教师，部署期不用」。
- 单任务测试通道只用于 A/B，不用于最终排名；最终提交仍是同一模型跑 32 任务。

| 方案 | 几何来源 | 场景表示 | 目标定位 | 人为干扰 | 学习模型数 | 本轮关系 |
|---|---|---|---|---|---|---|

| CHUNK-SERVO（第 12 轮） | 腕部/头部 2D | 目标图 | 2D 检索 | 2D 差分 | 1 | 保留；补米制目标/约束 |
| SIG-MPC（第 13 轮候选） | 双目实例图 | 实例图 | 实例绑定 | 无 | 1 | 合并离线分割/约束 MPC |

关键差异：

1. **米制**：从「2D 目标图/相似度」变成「桌面系 mm/deg 位姿」。
2. **锚定**：从「base/图像坐标」变成「桌面坐标」，直接吃位置/背景泛化。
3. **自运动补偿**：KIN-IMU 让 EDIT-ICP 能区分「机器人动了」和「场景被改了」。
4. **双目**：用官方基线丢弃的右头，成本最低的额外信息。
5. **合规**：几何层不是模型；GEO-TOKEN 同 checkpoint；不训第二个策略。

## 5. 可行性、资源、步骤、风险

### 5.1 资源

- **算力**：1×24 GB GPU 微调 WLA action head（官方默认）；1×GPU 离线跑双目/分割/模板；16–32 CPU 核做点云/ICP/QP；1–2 TB 存关键帧点云/模板/伪标签。

- **接口**：请求原生 480×640 头双目 + 腕部；`action_chunk_size` 5–8（握手期固定）；`control_space` joint/ee 二选一；N 端口从 8765 起。

## 6. 实验与消融

### 6.1 门

- **G0 标定门**：重建 `state_d435` 的平移误差 p95 ≤5 mm、旋转 ≤1°；对极误差 p95 ≤1 px；桌面法向误差 ≤2°；腕部重投影 ≤2 px。
- **G1 几何门**：刚性目标/受器位姿误差 p90 ≤10 mm/3°；配准 fitness ≥0.6；编辑检测 AUROC ≥0.9、误报 ≤5%；场景图目标角色准确率 ≥90%。
- **G2 伺服门**：仿真 5 任务碰撞率 ≤1%、目标误差 ≤5 mm、无关节限位；单任务通道 3/5 刚性任务 +10 pp，FoldTowel 不回归。
- **G3 token 门**：5 任务 +5 pp vs RGB-only WLA；dropout 后不回归；p99 ≤150 ms。
- **G4 部署门**：N 端口无串扰、reset 隔离、p99 ≤200 ms/chunk、显存 ≤24 GB/GPU、180 s 超时内完成。

### 6.2 消融

| 消融 | 问题 | 预期 |
|---|---|---|
| 双目 vs 左目单目 | 右眼值不值 | 双目在桌面/物体簇上更稳，透明件差距小 |
| 桌面系 vs base 系 | 锚定有没有用 | 桌面系在位置/背景泛化更好 |
| 演示点云配准 vs 2D 检索 | 3D 值不值 | 3D 在遮挡/视角变化更好，透明件可能更差 |
| EDIT-ICP vs 无 | 人为干扰值不值 | 20% 轴涨点，误报可控 |
| GEO-TOKEN vs 仅伺服 | token 值不值 | token 在语义/长程更好，伺服在最后 3 cm 更好 |
| URDF mask vs 无 | 自遮挡值不值 | mask 减少 ICP 离群点 |
| dropout vs 无 | 几何失败鲁棒性 | dropout 在几何缺失时不崩 |
| 精确 `state_d435` vs 重建 | 特权差距 | 重建 + 噪声训练缩小差距 |
| 5 步重规划 vs 30 步 | 闭环频率 | 5 步在接触段更好，但受 RTT 限制 |

### 6.3 指标与统计

- 主指标：成功率；次指标：步骤分、目标位姿误差、配准 fitness/RMSE、编辑 AUROC/延迟、碰撞率、p50/p99 延迟、端口隔离。
- 320 trials 的边缘 SE ≈2.5–2.8 pp；5 pp 的全局提升在显著边缘，必须看任务级一致性，不能只看总平均。
- 配对 A/B 用 McNemar；bootstrap 95% CI；预注册主指标和 5 任务 A/B，避免事后挑任务。

## 7. 竞赛策略

1. **先交安全基线**：用官方 WLA 微调一个 32 任务基线，锁定「更早提交」的 tie-break，拿真实分数；不要等几何层完美。
2. **单任务通道做 A/B**：选 5 个刚性几何任务（HangCup、PlugInEthernet、StackBowls、ArrangeTestTubes、Unlock）+ 1 个变形物任务（FoldTowel）做对照；不要用 32 任务全跑做早期消融。
3. **投资组合**：60% 外观泛化（干扰物/背景/未见物品）是几何层最大 ROI；20% 人为干扰是 EDIT-ICP 的差异化；20% 位置泛化靠桌面系重定位。先修「目标实例绑定」和「桌面系目标位姿」，再修「人为干扰」。
4. **N 端口**：共享 6B WLA 服务 + 每端口 CPU 几何；先测 N=4/8；每端口独立 reset/历史；p99 预算按 chunk 算，不按 30 Hz 算。
5. **安全/回退**：几何置信度低 → RGB-only WLA + 无约束伺服；编辑检测 → 下一 chunk 重规划/回撤；目标丢失 → 重观测，不盲抓。
6. **不做什么**：不把预览榜单当难度表；不加第二个在线模型；不做每任务策略；不做在线 SAM2；不做稠密 SLAM/3DGS 世界模型；不做 30 Hz 广域网伺服；不自适应 chunk size（握手期固定）。

## 8. 一句话押注

**用腰部 FK 替代 IMU、用双目点云配准替代深度相机，把四路 RGB 变成桌面锚定的米制场景图；WLA 负责语义，几何层负责最后 3 厘米和人为干扰，在不违反单模型规则的前提下补上 API 缺失的米制场景状态。**

# 第 13 轮产物 · ANCHOR-ICP 技术报告

> 检索/复核日期：**2026-10-29（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「ANCHOR-ICP」的工程化产物；承接第 12 轮 CHUNK-SERVO，吸收 `rounds/` 中 SIG-MPC 候选的离线实例分割与约束 MPC，不引入第二个在线学习模型。

## 0. 结论与边界

### 0.1 一句话结论

挑战赛 API 缺的不是 IMU，而是**桌面锚定的米制场景状态**：用 `lower_body[-3:]` 的腰关节 FK 重建头相机位姿（离线用数据集 `state_d435`/`state_torso` 标定固定变换），用桌面平面给重力，用右头双目点云配准给目标/受器位姿和人为干扰残差；WLA 仍是唯一学习模型负责语义与动作，确定性几何层负责最后 3 厘米、外观泛化和人为干扰。

| **C** | 论文/预印本，未独立复现 | StereoPolicy、PointWorld、ChronoGraph、Vision-Proprioception、Targeted Modality Dropout、Object-Centric Residual RL |

### 0.3 合规边界

- **单模型**：WLA 是唯一学习模型；几何层（SGBM/RANSAC/ICP/QP）没有学习权重；GEO-TOKEN 是同一 checkpoint 的 adapter。
- **离线教师**：SAM2/GroundingDINO 只用于离线标签/增强，不部署；部署期不跑第二个模型。
- **不改硬件**：不假设能加 IMU、深度相机、力/触觉；只使用 API 给的观测。
- **不伪造传感器**：KIN-IMU 是几何先验/自运动估计，不声称等于真实 IMU；不把估计值当测量值卖给 VLA。
- **不绕过评测**：不做 per-task 策略、不混合多模型、不利用测试集标签；单任务通道只做 A/B。

## 2. 问题定义与量化

### 2.1 为什么「缺 IMU」是错误的问题

三个事实：

1. API 不暴露 IMU；不能加硬件；官方 WLA Dex1 配置也不用 base inertial state。
2. 即使有 IMU，它只给重力方向/角速度，不给目标/受器的位姿、桌面平面、自由空间、人为干扰。
3. 数据里没有 IMU，但有 `state_d435`/`state_torso`/`waist_state_joint`；头相机位姿可由腰关节重建。**我们不需要 IMU 来补头相机外参，腰关节就是外参。**

所以正确的问题是：**如何在只有四路 RGB + 本体 + 语言的 API 上，在线得到桌面锚定的米制场景状态？**

### 2.2 米制场景状态的五个分量

| 分量 | 用途 | 本轮来源 |
|---|---|---|
| 桌面平面/重力 | 坐标锚、支撑面、基座倾角 | 双目点云 RANSAC + KIN-IMU |
| 机器人自运动 | 点云去畸变、编辑检测解释变量 | 腰/腿 FK + EE 跟踪误差 |
| 目标/受器位姿 | 伺服目标、抓取姿态、插入对齐 | 演示点云配准 + 腕部 2D |
| 自由空间/障碍 | 碰撞约束、路径 | 桌面系点云 + OBB |
| 场景编辑 | 人为干扰检测/恢复 | episode 地图 + ICP 残差 |

### 2.3 误差预算

最后 3 厘米的误差链：

```math
e_{total} \approx e_{calib} + e_{depth} + e_{register} + e_{servo} + e_{robot}
```

| 项 | 量级 | 说明 |
|---|---:|---|
| `e_calib` | 2–5 mm / 0.5–1° | KIN-IMU 重建 + 腕部标定；G0 控制 |
| `e_depth` | 1.5–15 mm | 0.5 m 处 0.1–1 px 视差；头双目 |
| `e_register` | 5–10 mm / 2–3° | 刚性物体 FPFH+RANSAC+ICP；透明/反光更差 |
| `e_servo` | 3–5 mm | 5 步约束 QP + 腕部近距 |
| `e_robot` | 1–3 mm | 关节跟踪/柔性 |

结论：**头双目 + 配准能到 1 cm 级，不能到 1 mm 级**；最后 1–2 mm 必须靠腕部近距（10–20 cm，腕部 fx≈436 px，1 px≈0.25–0.5 mm）或已知物体几何/模板。这个预算决定了：
- 头双目负责「找到、对准、避障」；
- 腕部/模板负责「最后插入/挂/拉链」；
- 不要承诺头双目毫米级。

### 2.4 泛化轴映射与收益上界

| 泛化轴 | 试次占比 | 几何层作用 | 预期（D 级） |
|---|---:|---|---|
| 干扰物 | 20% | 多簇标为 distractor/obstacle；目标角色绑定 | +5–10 pp |
| 桌面背景 | 20% | 桌面系归一化；几何不变 | +5–10 pp |
| 未见物品 | 20% | 模板低置信 → VLA 主导；几何给位姿/避障 | +0–5 pp |
| 位置 | 20% | 桌面系重定位 + 配准 | +5–10 pp |
| 人为干扰 | 20% | EDIT-ICP 检测 + 重规划 | +5–10 pp |

粗略上界：若外观三轴各 +10 pp（60% 权重）→ 全局 +6 pp；位置 +5 pp（20%）→ +1 pp；人为 +5 pp（20%）→ +1 pp；合计 **+8 pp 上界**。这是 D 级假设，不是承诺；实际可能 +2–5 pp。**不要用这个数字做宣传，用它做实验优先级。**

## 3. 方法

### 3.1 系统架构

```text
┌─────────────────────────────── 每个 chunk 边界 ───────────────────────────────┐
│                                                                              │
│  cam_left_high ─┐                                                            │
│  cam_right_high ├─→ 校正/双目 → 点云 → 桌面 RANSAC → 机器人 mask → 聚类/OBB   │
│  lower_body ────┼─→ KIN-IMU → T_base_d435 → 桌面系                            │
│  EE/gripper ────┘                         │                                   │
│                                           ├→ TABLE-SCENE（场景图）            │
│                                           ├→ ICP-TARGET（目标/受器位姿）      │
│                                           └→ EDIT-ICP（编辑分数）             │
│                                                                              │
│  cam_left_high + wrists + language ─→ WLA（6B，唯一学习模型）→ 30 步规划      │
│                                                                              │
│  TABLE-SCENE + 规划 ─→ CHUNK-SERVO（5 步约束 QP）→ 关节/EE 动作               │
│  TABLE-SCENE ────────→ GEO-TOKEN（可选）→ WLA action expert                   │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 KIN-IMU

#### 3.2.1 离线标定

数据里每帧有 `T_base_torso`（`state_torso`）和 `T_base_d435`（`state_d435`）。计算：

```math
T_{torso,d435} = \left(T_{base,torso}\right)^{-1} T_{base,d435}
```

在 HangCup 42 行样本上，平移 `[0.0576235, 0.0175300, 0.4298700] m`，变化 <1e-6 m；旋转恒定。G0 在 32 数据集上按机器人分组，检查平移/旋转的均值和方差；若某机器人不一致，用该机器人一小段数据重标定。

还需要：

- `T_base_torso` 的固定平移（样本 `[-0.004, 0, 0.044] m`）和腰关节到 rpy 的映射（样本 `[roll, pitch, yaw] = [waist_roll, waist_pitch, waist_yaw]`）。
- `T_d435,left_optical`：D435 机体到左目光学系的固定变换；从 URDF/`unitree_model` 或一次性标定来。
- 腕部 `T_ee,left_wrist_optical`/`T_ee,right_wrist_optical`：腕部相机到 EE 的固定变换；从 URDF/标定来；G0 用重投影验证。

#### 3.2.2 在线重建

API 给 `lower_body[-3:] = [waist_yaw, waist_roll, waist_pitch]`：

```math
T_{base,torso}(t) = \mathrm{Trans}(t_{torso}) \cdot R_z(q_{yaw}) R_y(q_{pitch}) R_x(q_{roll})
```

```math
T_{base,d435}(t) = T_{base,torso}(t) \cdot T_{torso,d435}
```

```math
T_{base,left\_optical}(t) = T_{base,d435}(t) \cdot T_{d435,left\_optical}
```

注意：rpy 顺序/符号必须用 URDF + 数据复核；上面的顺序是 HangCup 样本的经验，不是所有机器人通用。若腰关节有耦合/柔性，重建误差会变大；G0 用 `state_d435` 标签验证，p95 平移 ≤5 mm、旋转 ≤1°。

#### 3.2.3 桌面重力

```math
n_b = R_{base,left\_optical}(t) \cdot n_c
```

```math
\theta_{tilt} = \arccos\left(\frac{n_b \cdot e_z}{\|n_b\|}\right)
```

- 桌面水平：`n_b` 是 base 系「上」；`θ_tilt` 是基座 roll/pitch 估计。
- 桌面不水平：不要当重力；用标称直立/腿腰运动学；`gravity_confidence` 降低。
- 用途：桌面系 z 轴、基座倾角、伺服约束；不用于控制基座。

#### 3.2.4 身体摆动/接触代理

```math
s_{body} = [\Delta q_{leg}, \Delta q_{waist}, \dot{q}_{waist}, e_{ee}, \|e_{ee}\|]
```

- `Δq` 相对标称站姿；`e_ee = q_ee^{cmd} - q_ee^{state}`。
- 用途：伺服增益调度、EDIT-ICP 自运动解释、失败恢复。
- 不是 IMU：没有线加速度、没有高带宽角速度；不要声称等价。

#### 3.2.5 角速度（可选）

- 相邻 chunk 的 `T_base,d435` 差分；或用双目 VO。
- 桌面任务基座基本静止，角速度≈0；默认不用。
- 若用，必须做时间同步/滤波；不要把它塞进 WLA 的 base inertial state 假装是 IMU。

### 3.3 TABLE-SCENE

#### 3.3.1 双目校正与深度

1. 读 `camera_params.head_stereo` 的 K/R/T；用 Bouguet 校正（若 `rectified` 但左右 cx/cy 不一致，仍要校正）。
2. 验证对极误差：在 20–50 对匹配点上，`|y_left - y_right|` p95 ≤1 px；否则重新校正。
3. SGBM 参数（起点）：`minDisparity=0`，`numDisparities=128`（0.3–1.0 m），`blockSize=5–7`，`P1=8*3*bs²`，`P2=32*3*bs²`，`disp12MaxDiff=1`，`uniquenessRatio=10`，`speckleWindowSize=100`，`speckleRange=2`。
4. 左右一致性检查 + 小孔填充；只保留 ROI；体素下采样 2–5 cm。
5. 置信度：视差有效性、左右一致性、纹理/梯度、深度范围；低置信点不参与配准，只参与平面/避障。

#### 3.3.2 桌面平面

- ROI：机器人前方 0.2–0.9 m、横向 ±0.5 m、高度 0.5–1.0 m。
- RANSAC：3 点拟合，阈值 5–10 mm，迭代 200–500 次；选内点最多且法向与 `n_b` 夹角 <15° 的平面。
- 桌面系：原点取平面内机器人 base 投影；z 轴沿 `n_b`；x 轴取 base 前方在平面的投影；y 轴右手系。
- 检查：内点比例 ≥0.3；平面高度在合理范围；否则用上一帧平面/标称桌面高度。

#### 3.3.3 机器人自遮挡

- 用 G1 URDF + `left_arm/right_arm/lower_body` + gripper 状态做 FK；渲染上半身/手臂/夹爪到左头相机。
- 膨胀 mask 2–3 px；剔除 mask 内的点；对 mask 边缘做深度一致性检查。
- mask 不完美：trimmed ICP（只取内点）、RANSAC、颜色一致性；不要把机器人点当物体。
- 头部/躯干：用 `T_base,d435` 和 URDF 的相机安装变换渲染；注意近裁剪面。

#### 3.3.4 聚类与 OBB

- 去平面、去机器人后的点做欧氏聚类：半径 1.5–2.5 cm；最小簇 50 点（薄片/线缆降到 20）。
- 每簇：centroid、PCA/OBB（center、extent、yaw）、颜色直方图、点数、平均深度、置信度。
- 合并：距离 <2 cm 且颜色/高度一致的簇；拆分：细长物体用 PCA 主轴 + 腕部 2D。
- 透明/反光：点云可能只有边缘/背景；用腕部 2D 检测 + 模板；标记 `depth_conf` 低。

#### 3.3.5 角色绑定

- 离线任务模式表：`task_id/language -> target_category, receptacle_category, attributes`；确定性关键词 + 同义词；不部署 LLM。
- 在线：先按语言/任务给簇打类别；再用 ICP-TARGET 的模板匹配给实例；多候选时用颜色/尺寸/位置先验。
- 角色：`target`、`receptacle`、`distractor`、`obstacle`、`unknown`。
- 未见物品：模板低置信 → 角色退化为「语言类别 + 几何最可能」；VLA 主导；几何只给位姿/避障。
- 干扰物：多出来的簇标 `distractor/obstacle`；进避障约束，不进目标位姿。

#### 3.3.6 场景图

见想法区 3.3.6 的 JSON schema。补充：

- `frame: "table"`；所有位姿都是桌面系。
- `confidence` 由点数、深度有效性、配准 fitness、颜色一致性合成；低于阈值允许为空。
- `relations` 只保留任务需要的：`on`、`in`、`near`、`left_of`、`grasped_by`。
- 更新频率：每个 chunk 边界一次；缓存上一帧，避免抖动。

### 3.4 ICP-TARGET

#### 3.4.1 离线关键帧与模板

- 关键帧选择：接触前 0.3–0.5 s、释放前 0.3–0.5 s、EE 速度局部极小、夹爪开合变化、阶段标签切换。
- 用 `state_d435`（精确头相机位姿）+ 双目深度把关键帧转到桌面系；存目标/受器簇点云、OBB、颜色、相对 EE 位姿。
- 每任务 20–100 个模板；按类别/受器/阶段聚类；每任务 <50 MB。
- 数据增强：随机下采样、法向噪声、颜色抖动、遮挡（随机删点）；让模板配准见过噪声。

#### 3.4.2 在线配准

```text
输入：P_live（桌面系，去机器人/去平面），Templates（目标/受器）
1. 对 P_live 和每个模板算 FPFH（半径 0.03 m，max_nn 50）。
2. RANSAC 全局配准：距离阈值 0.015 m，迭代 50k–100k，取 top-k 变换。
3. 对每个候选做 trimmed ICP（点到面，trim 20–30%，迭代 30–50）。
4. 选 fitness 最高且 RMSE 最低的模板/变换。
5. 输出 T_table_obj / T_table_rec、fitness、RMSE、inlier_ratio。
6. 目标 EE：T_base_ee* = T_base_table * T_table_obj * T_obj_ee_demo。
```

- 初始化：桌面系 + 簇 centroid + 主轴；减少 RANSAC 搜索。
- 多模板：同类别多模板；取 top-3；若 top-1 与 top-2 差异大，降低置信度。
- 颜色：在 RANSAC 后做颜色一致性检查；避免把相似形状的干扰物配到目标。
- 透明/反光：点云少 → 用腕部 2D + 模板轮廓；配准只做粗对齐。

#### 3.4.3 置信度门控

| fitness | RMSE | 用途 |
|---:|---:|---|
| ≥0.6 | ≤1.5 cm | 接受几何目标位姿 |
| 0.4–0.6 | ≤2.5 cm | 只用于避障/约束 |
| <0.4 | — | 几何降级；目标位姿交给 VLA/腕部 |

阈值按任务在 G1 上标定；不要全局常数。

### 3.5 EDIT-ICP

#### 3.5.1 地图

- `M_0`：episode 开始/第一个 chunk 的桌面系点云 + 物体簇 + 角色。
- 每个 chunk：`P_t` 配准到 `M`（桌面系已知，ICP 只做小修正）；更新 `M`（指数滑动平均，α=0.3–0.5；只更新静态簇）。
- 地图只保留桌面 ROI + 物体簇；不建稠密 SLAM；内存 10–50 MB/端口。

#### 3.5.2 残差与编辑分数

```math
r(x) = \left\| \mathrm{ICP}(P_t, M) - M \right\|
```

剔除：

- 机器人本体（URDF mask）；
- 已抓取物体（EE pose + gripper + 模板）；
- 预期运动（VLA 计划/EE 轨迹附近）；
- 深度低置信点。

残差簇：

- 位移 >3 cm 或点数 >阈值；
- 连续 2 个 chunk 出现；
- 在目标/受器附近或任务相关区域。

编辑分数：

```math
s_{edit} = \sigma\left(w_0 + w_1 \cdot \frac{n_{res}}{n_{obj}} + w_2 \cdot \frac{d_{res}}{d_{max}} + w_3 \cdot \mathbb{1}_{near\_target}\right)
```

权重在 G1 上用合成编辑标定；输出 `edit_score`、区域 centroid、类型（move/add/remove）。

#### 3.5.3 恢复

- chunk 内不能打断；最快在下一个 chunk 边界。
- 重新跑 TABLE-SCENE/ICP-TARGET；更新目标位姿。
- WLA 重新规划或伺服追新目标。
- 目标被拿走/不可恢复：安全回撤/重观测，不盲抓。
- 连续误检：降低灵敏度/要求 3 个 chunk；避免频繁停顿。

### 3.6 GEO-TOKEN（可选第二级）

#### 3.6.1 schema

| 组 | 维度 | 内容 |
|---|---:|---|
| table | 4 | 法向 3 + 偏移 1 |
| gravity/body | 3 | base tilt roll/pitch + confidence |
| target | 10 | centroid 3 + extent 3 + yaw 1 + confidence 1 + fitness 1 + rmse 1 |
| receptacle | 10 | pose 6 + aperture 2 + confidence 1 + fitness 1 |
| distractors/obstacles | 6K | K=4：centroid 3 + extent 3 |
| body proxy | 8 | waist 3 + leg deviation 2 + EE error 2 + contact 1 |
| edit | 4 | edit score 1 + region centroid 3 |
| **合计** | **63** | K=4 |

#### 3.6.2 adapter 与训练

- 63 → LayerNorm → MLP（63→256→token_dim）→ 1–4 tokens。
- 与 WLA state tokens 拼接或 cross-attend；只训 adapter + action head；VLM/DiT 主干冻结。
- 训练目标：动作损失（沿用 WLA）；可选辅助：目标位姿预测/对比对齐；不要加太多辅助损失。
- 模态 dropout：整块 p=0.2；单组 p=0.1；测试按置信度门控。
- 离线/在线混合：精确 `state_d435` vs 重建位姿 + 标定噪声；让 adapter 见过在线误差。
- 若 WLA 代码集成成本高：第一级只做「几何 + 伺服」；不要为了 token 改坏基线。

### 3.7 CHUNK-SERVO 约束 QP

#### 3.7.1 变量与动力学

- 决策变量：`u_{0:H-1}`（EE 增量或关节增量），`H=5`。
- 状态：EE 位姿/关节角；用简单运动学 `x_{k+1} = f(x_k, u_k)`；不用学习动力学。
- 目标：`x_k^{target}` 来自 ICP-TARGET + WLA 规划；接触段用法向缩幅。

#### 3.7.2 约束

- 桌面：`z_ee ≥ z_table + margin`（除接触阶段）。
- 障碍：distractor/obstacle OBB 膨胀 2 cm；EE/夹爪点不在 OBB 内。
- 关节限位/速度：URDF + 当前 `lower_body`；`|u_k| ≤ u_max`。
- 视野：目标/受器投影在图像边界内（留 10% 余量）。
- 夹爪：目标 OBB 宽度 vs 开口；抓取姿态可行。
- 接触：法向速度 ≤ `v_contact`；增益/步长降。

#### 3.7.3 求解与 timing

- 10–15 步 QP；OSQP/qpOASES/自写小 QP；CPU 1–5 ms。
- 每 5 步重规划；块内开环；反馈周期 `H_c/f_c + τ`，H_c=5、f_c=30、τ=50 ms → 约 217 ms。
- 若 QP 不可行：放松障碍/视野约束（硬约束→软约束），保桌面/关节限位；仍不可行则回退到无约束 VLA 动作。

### 3.8 全链路伪代码

```python
# 每个 chunk 边界
def step(obs, state):
    # 1. KIN-IMU
    T_base_d435 = kin_imu(state.lower_body[-3:])
    T_base_left = T_base_d435 @ T_d435_left_optical

    # 2. 双目几何
    rect = rectify(obs.cam_left_high, obs.cam_right_high, calib)
    depth, conf = sgbm(rect)
    P_cam = backproject(depth, calib)
    P_base = transform(P_cam, T_base_left)
    P_table = transform(P_base, inv(T_base_table))

    # 3. 场景图
    plane = ransac_plane(P_table, roi)
    P_obj = remove_plane(P_table, plane)
    P_obj = remove_robot(P_obj, urdf_mask(state))
    clusters = euclidean_cluster(P_obj)
    graph = build_scene_graph(clusters, plane, state, language)

    # 4. 目标/受器配准
    target = icp_target(graph, templates, P_obj)
    graph.update(target)

    # 5. 人为干扰
    edit = edit_icp(P_table, episode_map, graph, state)
    graph.update(edit)

    # 6. VLA 规划（唯一学习模型）
    plan = wla(obs.cam_left_high, obs.cam_left_wrist, obs.cam_right_wrist,
               state, language, geometry_tokens(graph) if use_tokens else None)

    # 7. 约束伺服
    actions = chunk_servo(plan, graph, state, H=5)
    return actions
```

| 欧氏聚类 + OBB | CPU | 5–15 ms | 每 chunk |
| FPFH + RANSAC + ICP（2k 点） | CPU | 30–80 ms | 每 chunk |
| EDIT-ICP | CPU | 10–30 ms | 每 chunk |
| QP | CPU | 1–5 ms | 每 5 步 |
| WLA 6B 推理 | GPU | 100–300 ms | 每 chunk |
| 网络 RTT | — | 10–150 ms | 每 chunk |

几何层总计 50–150 ms（可与 WLA 推理重叠）；端到端反馈 200–320 ms（5 步 chunk + RTT）。**不要声称 30 Hz 闭环**；这是每 chunk 一次的几何更新 + 5 步开环执行。

### 5.3 任务选择

单任务通道 A/B 建议：

- **刚性几何**：HangCup（挂杯）、PlugInEthernet（插网线）、StackBowls（叠碗）、ArrangeTestTubes（试管架）、Unlock（开锁）。
- **变形物对照**：FoldTowel（折毛巾）——几何层预期收益小，用来检查「不回归」。
- **未见物品**：选一个同类不同外观的替换物；只测几何回退，不测模板匹配。
- **人为干扰**：在目标/受器附近移动 5–20 cm；测 EDIT-ICP 延迟/恢复。

如果只能选 3 个：HangCup（挂/接触）、PlugInEthernet（插入/细对齐）、FoldTowel（对照）。

### 5.4 统计

- 320 trials 边缘 SE ≈ `sqrt(p(1-p)/320)`；p=0.3 时 ≈2.56 pp，p=0.5 时 ≈2.80 pp。
- 5 pp 全局提升在显著边缘；必须看任务级一致性，不能只看总平均。
- 配对 A/B 用 McNemar；bootstrap 95% CI；预注册主指标（成功率）和 5 任务 A/B。
- 不要事后挑任务/挑 seed；不要用预览榜单的任务排名做分层。

## 6. 竞赛策略

### 6.1 投资组合

| 优先级 | 工作 | 理由 | 预期 |
|---|---|---|---|
| P0 | 官方 WLA 32 任务基线 + 安全提交 | 锁 tie-break、拿真实分数 | 基线 |
| P1 | KIN-IMU + TABLE-SCENE + ICP-TARGET | 60% 外观泛化 + 20% 位置 | +2–5 pp |
| P2 | CHUNK-SERVO 约束 QP | 最后 3 cm、碰撞 | +1–3 pp |
| P3 | EDIT-ICP | 20% 人为干扰 | +1–2 pp |
| P4 | GEO-TOKEN | 语义/长程；可选 | +0–2 pp |
| P5 | 未见物品回退 | 防回归 | 保底 |

### 6.2 提交/端口/延迟

- 先交安全基线；再交几何层；最后交 token。
- 单任务通道做 A/B；32 任务全跑只在 G2/G3 过门后。
- N 端口：共享 6B WLA + 每端口 CPU 几何；先测 N=4/8；每端口独立 reset/历史。
- p99 按 chunk 算：几何 50–150 ms + WLA 100–300 ms + RTT 10–150 ms；目标 ≤200 ms/chunk（几何与 WLA 重叠）。
- 若评测端要求更紧：降低点云分辨率/ROI、每 2 个 chunk 跑一次几何、模板缓存。

### 6.3 安全/回退

- 几何置信度低 → RGB-only WLA + 无约束伺服。
- 编辑检测 → 下一 chunk 重规划/回撤。
- 目标丢失 → 重观测，不盲抓。
- QP 不可行 → 放松软约束；仍不可行 → VLA 原动作。
- 端口异常 → 独立进程/健康检查；不要让一个端口拖垮全部。

### 6.4 不做什么

- 不把预览榜单当难度表/SOTA。
- 不加第二个在线模型（SAM2/GroundingDINO/6D pose/世界模型）。
- 不做每任务策略/多模型混合。
- 不做在线稠密 SLAM/3DGS。
- 不做 30 Hz 广域网伺服。
- 不自适应 chunk size。
- 不承诺头双目毫米级；最后 1–2 mm 用腕部/模板。
