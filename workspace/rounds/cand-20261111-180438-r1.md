# 第 55 轮（承接第 54 轮 v31 GroundEdge-GenSim+++；灵感循环第 6 轮；本轮灵感：「数据采集」×「用户体验」）

> 第 54 轮把技能组合推进为动作空间剖面 α_S 与云边联合证书 J，但其全部证据都默认来自“充分、无偏、可随时获取”的采集过程。本轮把镜头转向**证据的生产端**：聚焦 **采集策略的体验约束、用户战略性回避造成的选择偏差、以及证据证书的可迁移性**。核心矛盾：H22：鲁棒性/动作证书要求密集采集，而密集采集消耗延迟、注意力、隐私与信任，用户会策略性回避，使采集分布 q 与部署分布 p 系统性错配（observer effect / selection bias）；H23：用户体验被当作事后满意度指标而非采集约束，导致“证书越强、体验越差、数据越偏”的三输。

## 0. 直觉与动机

**灵感 1（采集不是中立的：观测改变被观测者）**
直觉：上一轮 α_S、ρ 的所有证据都来自“请求-响应”式采集。但采集动作本身有体验成本 `ux(a)=(u_lat,u_int,u_priv,u_cog)`。用户不是被动传感器：高成本采集会被忽略、敷衍或规避，于是**采集到的样本分布 q(x) 与部署分布 p(x) 不一致**。证书若只在 q 上成立，就会在 p 上系统性高估能力。观测行为改变了被观测分布——这是数据采集版的 observer effect，也是第 54 轮 α_S“虚假兼容”更深的根因：不是采样少，而是采样偏。

**灵感 2（用户体验是采集的约束，不是事后指标）**
直觉：若把 UX 当作部署后的满意度分数，最优策略必然是“多采多证”，直到体验崩塌、用户流失、数据更偏。正确做法是把体验成本作为采集策略的**显式预算**：在 `U_π(T) ≤ B_ux` 的约束下最大化证据增益。这把“采集多少”从无约束最大化，变成“在体验预算内采哪里”的受限优化（CMDP / constrained bandit）。

**灵感 3（战略性用户 → 接受倾向可建模）**
直觉：用户对采集动作 a 的接受概率随体验成本单调下降。用 logistic 倾向建模 `p_acc(a)=σ(β·(θ_ux−⟨w,ux(a)⟩))`。这给出采集分布 `q(x) ∝ p_acc(a(x))·p(x)`，把“用户为什么回避”变成可估计、可校正的统计量，而不是一句“数据有偏”。

**灵感 4（偏差可校正 ≠ 校正可用 → ESS 守门）**
直觉：用重要性重加权 `w=p/q` 可把 q 上的风险无偏迁移到 p，但 `χ²(p‖q)` 一大，有效样本量 ESS 就崩塌。证书必须同时记录 **偏差界 δ_bias 与 ESS**：偏差可证、且校正后仍有统计功效，才能部署；否则触发定向补采（在密度比最高的区域补样本）。

**灵感 5（证据-体验联合证书 → 金字塔再叠一层“证据层”）**
直觉：在第 54 轮动作-鲁棒性双证书 `J` 之上，叠加 **证据层 `𝔼`**：`𝔼_0` 原始采集日志与同意来源，`𝔼_1` 接受倾向与采集分布 q，`𝔼_2` 偏差界与 ESS，`𝔼_3` 校正后的可部署证书。跨层证书 `J+=(J,C_evi,C_ux)` 保证：不仅能力可证，而且“证它的数据”本身可信、可追溯、且获取过程不伤害体验。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（采集动作与体验成本）**
采集动作空间 `A_col = A_c × A_e × M`，`M` 为模态/时机维度。采集策略 `π: H_t → Δ(A_col)`。单步体验成本向量 `ux(a)=(u_lat,u_int,u_priv,u_cog) ∈ ℝ₊⁴`。会话体验预算 `B_ux`，累计成本 `U_π(T)=Σ_t ux(a_t)`。采集可行当且仅当 `U_π(T) ≤ B_ux` 逐分量成立。

**定义 122（体验约束采集，UX-CMDP）**
`M_ux=(S, A_col, P, r_evi, ux)`，目标
```
max_π  E_π[Σ_t r_evi(s_t,a_t)]   s.t.  E_π[Σ_t ux_i(s_t,a_t)] ≤ b_i,  i∈{lat,int,priv,cog}
```
其中证据增益 `r_evi = IG(x_t | H_{t-1})`（信息增益）或覆盖增量 `Δcov`。约束满足率记为 `κ_ux`。

**定义 123（用户接受/回避模型）**
用户对动作 a 的接受倾向 `p_acc(a)=σ(β·(θ_ux − ⟨w, ux(a)⟩))`。采集分布
```
q(x) = p_acc(a(x))·p(x) / Z,   Z = ∫ p_acc(a(x)) p(x) dx
```
部署分布为 `p(x)`。选择偏差 `δ_bias = sup_{ℓ∈𝓛} |E_q[ℓ] − E_p[ℓ]| ≤ D_TV(p,q)`，`𝓛` 为证书关心的有界损失类。正性假设 `p(x)>0 ⇒ q(x)>0`。

**定义 124（采集覆盖与证据强度证书）**
`C_evi = (Supp, ε_cov, ESS, δ_bias)`：
- `Supp` 为采集支撑集，`ε_cov = 1 − ∫_Supp p(x)dx` 为部署质量未覆盖比例；
- `ESS = (Σ_i w_i)² / Σ_i w_i²`，`w_i = p(x_i)/q(x_i)`；
- `δ_bias` 为定义 123 的偏差上界。
证书**可用**当且仅当 `ε_cov ≤ θ_cov ∧ ESS ≥ N_min ∧ δ_bias ≤ Θ_bias`。

**定义 125（证据-体验联合证书）**
`J+ = (J, C_evi, C_ux)`：
- `J` 为第 54 轮动作-鲁棒性联合证书；
- `C_evi` 为定义 124 的证据强度证书；
- `C_ux = (U_π, B_ux, κ_ux, consent, provenance, reversibility)`，其中 `consent` 为同意范围，`provenance` 为逐条证据到采集动作的可追溯链，`reversibility` 为撤回/删除能力。
部署判据：`dom_J(T)=in ∧ δ_a<Θ_a ∧ C_evi 可用 ∧ κ_ux ≥ κ_min ∧ provenance 完备`。

**定义 126（偏差校正的可部署判据）**
令 `R̂_q^IPW(π_skill)=(1/n)Σ_i w(x_i)ℓ_i`。在 (A29)–(A32) 下，以概率 `≥1−δ`：
```
R_p(π_skill) ≤ R̂_q^IPW(π_skill) + δ_bias + c·√(log(1/δ)/ESS)
```
若右端 `≤ ρ_min` 则可部署；否则触发**定向补采** `recollect(R*)`，其中
`R* = argmax_{R⊆Supp} p(R)/q(R)`（密度比最大、对 ESS 拖累最重的区域）。

## 2. 关键算法 伪代码

### IP-121 UCP（UX-Constrained Collection Policy）

```python
def ux_constrained_collect(env, B_ux, theta_ux, horizon):
    pi = init_policy()
    spent = {k: 0.0 for k in ('lat','int','priv','cog')}
    buffer = []
    for t in range(horizon):
        s = env.state()
        a = pi.sample(s)
        fc = env.ux_cost_forecast(a)              # 预测体验成本
        if any(spent[k] + fc[k] > B_ux[k] for k in spent):
            a = pi.sample_low_ux(s)               # 投影到体验可行域
        if ux_shield(a, fc, theta_ux) != 'allow':
            continue                              # 被护栏否决则不采
        x, ux = env.collect(a)
        for k in spent: spent[k] += ux[k]
        buffer.append((a, x, ux))
        update_policy(pi, evidence_gain(x), ux)   # 拉格朗日/CMDP 对偶更新
    return pi, buffer
```

### IP-122 UAM（User Acceptance Model）

```python
def fit_acceptance(collection_log):
    # p_acc(a) = sigmoid(beta * (theta_ux - w·ux(a)))
    X = [[1.0] + ux_vector(row) for row in collection_log]
    y = [int(row.responded) for row in collection_log]
    beta_theta, w = fit_logistic(X, y)
    return lambda a: sigmoid(beta_theta - dot(w, ux_vector(a)))
```

### IP-123 BIW（Bias-aware Importance reWeighting）

```python
def bias_aware_reweight(evidence, p_deploy, q_collect, N_min, Theta_bias):
    w = []
    for x in evidence:
        qx = max(q_collect(x), 1e-9)
        w.append(p_deploy(x) / qx)
    ess = sum(w)**2 / max(sum(wi*wi for wi in w), 1e-12)
    delta_bias = tv_distance(p_deploy, q_collect)
    if ess < N_min or delta_bias > Theta_bias:
        return ('insufficient', ess, delta_bias)   # 拒绝并建议补采
    return ('ok', w, ess, delta_bias)
```

### IP-124 UXS（UX Shield）

```python
def ux_shield(a, ux_forecast, contract):
    for k in ('lat','int','priv','cog'):
        if ux_forecast[k] > contract.budget[k]:
            return ('veto', f'ux_budget:{k}')
    if not consent_scope_ok(a, contract.consent):
        return ('veto', 'consent_scope')
    if not contract.reversible(a):
        return ('veto', 'irreversible')
    return ('allow', a)
```

### IP-125 EJC（Evidence-UX Joint Certificate）

```python
def joint_evidence_certificate(J, evidence, p_deploy, q_collect, C_ux):
    status, w, ess, delta_bias = bias_aware_reweight(
        evidence, p_deploy, q_collect, N_min, Theta_bias)
    if status != 'ok':
        return ('reject', 'evidence_insufficient', ess, delta_bias)
    if C_ux.compliance_rate < kappa_min or not C_ux.provenance_complete:
        return ('reject', 'ux_or_provenance_violation')
    R_hat = ipw_risk(evidence, w, J.skill_seq)
    bound = R_hat + delta_bias + c * sqrt(log(1/delta) / ess)
    if bound > rho_min:
        return ('reject', 'certified_risk_too_high', bound)
    return ('ok', EJC(J, C_evi=(w, ess, delta_bias), C_ux=C_ux, bound=bound))
```

### IP-126 TRC（Targeted ReCollection）

```python
def targeted_recollect(evidence, p_deploy, q_collect, failed_dims):
    # 选密度比最大、对 ESS 拖累最重的区域补采
    R_star = argmax_region(lambda R: p_deploy(R) / max(q_collect(R), 1e-9))
    plan = []
    for dim in failed_dims:
        a = choose_action_touching(R_star, dim, budget=min_ux_cost)
        plan.append(a)
    return plan   # 交回 UCP，并冻结失败维度对应的证书
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| UCP | O(T·(|A_col|+d_ux)) | O(T) | 约束投影可行、对偶收敛 |
| UAM | O(n·d_ux²) | O(d_ux²) | 倾向模型可识别、正性假设 |
| BIW | O(n·d_x) | O(n) | 正性、权重有界、ESS≥N_min |
| UXS | O(d_ux) | O(1) | 契约逐分量 sound、consent 完备 |
| EJC | O(n·d_x+𝔇_ρ) | O(n) | 偏差界闭合、证书可追溯 |
| TRC | O(|𝓡|·d_x) | O(|𝓡|) | 密度比估计准确、补采覆盖目标区 |

**正确性定理（UX-Evidence Transfer Soundness）**
假设第 54 轮 (A22)–(A28) 成立；**(A29)** 接受倾向模型正确设定或误设误差 ≤ ε_m；**(A30)** 正性 `p(x)>0 ⇒ q(x)>0` 且 `w=p/q` 有界；**(A31)** UX 护栏在会话内无违约（`κ_ux=1`）；**(A32)** 覆盖证书 `ε_cov ≤ θ_cov` 可判定。则以概率 `≥1−δ`：
```
|R_p(π_skill) − R̂_q^IPW(π_skill)| ≤ δ_bias + ε_m + c·√(log(1/δ)/ESS)
P_success ≥ 1 − Σ_d(1−ρ_min(d)) − β_E − P(δ_a>Θ_a) − [δ_bias + ε_m + c·√(log(1/δ)/ESS)]
```
关键：**证据分布必须校正回部署分布**，**校正后必须仍有统计功效（ESS）**，**体验护栏保证 q 的生成过程可解释且可追溯**。

## 4. 实验设计 E162–E166

| 实验 | 指标 | 目标 |
|---|---|---|
| E162 采集-体验 Pareto | 证据增益 vs `U_π` | 同等体验预算下覆盖提升 ≥ 15% |
| E163 响应偏差导致的证书落差 | `R_p − R_q` | 无校正时 ≤ 5% 视为“高危偏差”告警 |
| E164 偏差校正有效性 | IPW 校正后落差 / ESS | 落差 ≤ 2%，ESS ≥ 200 |
| E165 体验护栏合规性 | 违约率 `1−κ_ux` / 投诉率 | 违约率 ≤ 0.5%，投诉不升 |
| E166 定向补采收益 | 补采后 ESS / 覆盖率提升 | ESS 提升 ≥ 2×，覆盖 ≥ θ_cov |

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 用户战略性回避导致 q 极端偏斜 | 高 | 主动探索小成本动作 + 密度比监控 + 定向补采 |
| 重加权后 ESS 崩塌 | 高 | ESS 硬门槛 + 自适应最小样本 + 拒绝部署 |
| 倾向模型误设 | 高 | 双重稳健估计（IPW+结果模型）+ 红队校准 |
| 隐私/同意边界模糊 | 高 | 形式化 consent 范围 + provenance 追链 + 可撤回 |
| UX 约束使关键区域永远采不到 | 中 | 分层配额 + 差分隐私替代采集 + 仿真先验 |

## 6. 本轮最大风险

**一句话**：把用户体验立为采集的显式约束后，系统会自发收敛到“低成本可采区”，使采集分布 q 与部署分布 p 系统性错配——用重要性重加权虽可把证书迁移回 p，却又把有效样本量 ESS 压到崩塌，形成“体验越好、数据越偏、证书越假”的悖论；因此必须把 **可证偏差界 δ_bias、最小 ESS 硬门槛、以及 consent/provenance 三重审计** 作为部署前置，宁可承认“证据不足”而拒绝部署，也绝不把体验友好的稀疏偏样本包装成完备证据。

# 第 55 轮产物 · 创新点清单 v32：GroundEdge-UXEvidence（UCP×UAM×BIW×UXS×EJC×TRC）

> 承接第 54 轮产物 v31。本轮不再问“技能能否组合”，而问“**证明它能组合的证据本身是否可信、获取过程是否伤害用户体验**”。新增 **证据生产层** 六大算子：
> - **UCP（UX-Constrained Collection Policy）**：体验预算约束下的采集策略（UX-CMDP）；
> - **UAM（User Acceptance Model）**：用户接受/回避倾向建模，量化选择偏差来源；
> - **BIW（Bias-aware Importance reWeighting）**：把 q 上的证据校正回部署分布 p，并守门 ESS；
> - **UXS（UX Shield）**：延迟/打扰/隐私/认知 + consent 的在线护栏；
> - **EJC（Evidence-UX Joint Certificate）**：在 J 上叠加证据强度与体验契约；
> - **TRC（Targeted ReCollection）**：偏差/功效不达标时的定向补采。
>
> IP 编号：IP-121~IP-126（共 6 个新增），升级 IP-115/118/120 以纳入证据维度。

```python
    if C_ux.compliance_rate < kappa_min or not C_ux.provenance_complete:
        return ('reject', 'ux_or_provenance_violation')
    R_hat = ipw_risk(evidence, w, J.skill_seq)
    bound = R_hat + delta_bias + c * sqrt(log(1.0/delta) / ess)
    if bound > rho_min:
        return ('reject', 'certified_risk_too_high', bound)
    return ('ok', EJC(J, C_evi=(w, ess, delta_bias), C_ux=C_ux, bound=bound))
```

## 3. 推导：偏差如何进入部署成功率

IPW 估计量 `R̂_q^IPW=(1/n)Σ_i w(x_i)ℓ(x_i)`，`w=p/q`。在正性假设 (A30) 下 `E_q[wℓ]=E_p[ℓ]`，故误差只有估计误差与模型误设两项。令 `χ²(p‖q)=E_q[(p/q)²]−1`，则 `Var_q(wℓ) ∝ χ²(p‖q)`，而
```
ESS ≈ n / (1 + χ²(p‖q))
```
由 Bernstein/经验过程界，以概率 `≥1−δ`：
```
|R_p − R̂_q^IPW| ≤ δ_bias + ε_m + c·√(log(1/δ)/ESS)
```
把它代入第 54 轮的动作-鲁棒性成功率下界：
```
P_success ≥ 1 − Σ_d(1−ρ_min(d)) − β_E − P(δ_a>Θ_a)
            − [δ_bias + ε_m + c·√(log(1/δ)/ESS)]
```
**推论（体验-证据悖论）**：若 UX 预算收紧使高价值区域 `p_acc→0`，则 `q` 在该区域质量趋零、`p/q→∞`、`χ²→∞`、`ESS→0`，校正项发散。因此“提升体验”与“提升证据强度”在缺少主动探索时分道扬镳——必须用 TRC 在关键区域以最小体验成本换取正性，或改用差分隐私/仿真先验替代。

## 6. 本轮最大风险

**一句话**：把用户体验立为采集的显式约束后，系统会自发收敛到“低成本可采区”，使采集分布 q 与部署分布 p 系统性错配——用重要性重加权虽可把证书迁移回 p，却又把有效样本量 ESS 压到崩塌，形成“体验越好、数据越偏、证书越假”的悖论；因此必须把 **可证偏差界 δ_bias、最小 ESS 硬门槛、以及 consent/provenance 三重审计** 作为部署前置，宁可承认“证据不足”而拒绝部署，也绝不把体验友好的稀疏偏样本包装成完备证据。
