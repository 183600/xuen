## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（实时推理 → 延迟不是吞吐指标，是安全裕度）**
直觉：多数队伍把推理延迟当工程问题——p99 越低越好，却说不清“够用”的标准。人机协作正好给出标准：**人手接近速度决定安全预算**。若人手以 0.5 m/s 进入工作区，安全间距 10cm、制动距离 5cm，则允许反应时间约 100ms。而官方默认动作块 16 步、控制 15Hz（F12）：若 evaluator 按块开环执行，一个 chunk 就是 1.07s 的“反应死区”——手已经走了 53cm。**再准的手部检测器，也救不了一个 1s 不更新的策略。** 所以实时推理的第一性问题是“反应死区 L_r”，不是“平均延迟”。

严谨定义：令控制频率 f_c、块长 T_a、推理尾延迟 Q_α(L_infer)、网络 L_net。
- 按块开环：L_r = T_a/f_c + Q_α(L_infer) + L_net；
- 逐 step 调用：L_r = Q_α(L_infer) + L_net。
安全预算 B = (d_safe − d_stop)/v_rel。要求 L_r < B。
在 f_c=15Hz 下，T_a=1/2/4/8/16 的死区分别为 67/133/267/533/1067ms。取 v_rel=0.5m/s、d_safe−d_stop=5cm → B=100ms，则**按块语义下 T_a≤1 才勉强安全**；逐 step 语义下块长只影响推理摊销，不影响反应。两种语义的最优解相差一个数量级——这是本轮必须先确认的事实（F22）。

**灵感 2（人机协作 → 没有力传感器，但有一个免费的伪力通道）**
直觉：官方接口没有力/触觉（F8），大家把接触当视觉问题。但评测执行的是我们下发的动作，我们能看到执行后的本体状态——**命令与观测的残差就是外力**。人推机器人、挪走物体、递物，会在残差上留下不同签名。更妙的是，用 I5 的进度头 Φ(s) 判断人的位移是“帮忙”还是“捣乱”：残差把状态推向更高得分点就是协助，反之是阻碍。于是协作从被动避让变成“读懂意图再决定让/抗/接”。

严谨定义：令 s_t 为本体状态（关节/ee+gripper），a_{t−1} 为已执行目标，ŝ_t = s_{t−1} + clip(a_{t−1}−s_{t−1}) 为无外力预测，残差 r_t = s_t − ŝ_t，伪力 d_t = sqrt(r_t^T Σ_nom^{-1} r_t)（Σ_nom 由标称 episode 标定）。意图 I_t = sign(Φ(s_t) − Φ(ŝ_t))；|d_t| 小且 I_t≈0 为无干扰，d_t 大且 I_t<0 为阻碍，I_t>0 为协助。

**灵感 3（两者统一 → 协作是带截止时间的控制问题）**
直觉：实时推理回答“来不来得及反应”，人机协作回答“该反应什么”。合起来是一个 deadline-constrained interaction protocol：检测→分类→响应必须在 B 内完成，且响应本身要平滑（否则动作异常会被可信度检查扣分，F23）。这把 I4 从“检测到就停”升级为“按模式响应 + 按预算调度”。

严谨定义：协作响应策略 π_c(a_t | s_t, m_t, Φ)，m_t ∈ {M1 穿越, M2 物体位移, M3 物理推挤, M4 递物/协助}，约束 L_r < B_collision（≈100ms）且动作二阶差分 S_t < S_max；意图识别可用更松的 B_intent（≈500ms）。系统是双速率：慢 VLA 负责语义/规划，快反射负责安全/协作。

**统一结论**：本轮胜负手从“数据侧”部分转向“交互侧”——**人类干扰占 20% 评测且是唯一能被策略即时干预的轴；而它的瓶颈不在感知，在反应时。**

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2）

> 检索日期：2026-11-27；来源见 §6。承接 v1.1：新增 I10/I11/I12，深化 I4/I6/I8；I1/I2/I5/I9 维持。清单只增改不重置。

## 0. 核心推导：反应预算、块死区与伪力

### 0.1 反应死区与安全预算

设控制频率 f_c、动作块长 T_a、推理尾延迟 Q_α、网络时延 L_net：

- 按块开环执行（README §3 字面）：`L_r = T_a/f_c + Q_α(L_infer) + L_net`
- 逐 step 调用（`run_client.py` 行为）：`L_r = Q_α(L_infer) + L_net`

安全预算 `B = (d_safe − d_stop)/v_rel`。要求 `L_r < B`。

| T_a（f_c=15Hz） | 1 | 2 | 4 | 8 | 16 |
|---|---|---|---|---|---|
| 块死区 T_a/f_c | 67ms | 133ms | 267ms | 533ms | 1067ms |
| 人手位移 @0.5m/s | 3.3cm | 6.7cm | 13.3cm | 26.7cm | 53.3cm |

| v_rel | 0.3 | 0.5 | 0.8 | 1.0 m/s |
|---|---|---|---|---|
| B（d_safe−d_stop=5cm） | 167ms | 100ms | 63ms | 50ms |

**结论**：
1. 按块语义下，B=100ms 时 T_a≤1 才勉强安全；T_a=2 仅当 v_rel≤0.3 或净距≥10cm 才可接受。
2. 逐 step 语义下，块长只影响推理摊销；反应由推理尾延迟决定。
3. 异步流水只能消除“推理叠加在块上”的额外延迟，**不能突破块边界**；因此 F22 是方案分叉点。
4. 反应-摊销前沿：每秒算力 `C(T_a)=f_c·c_infer/T_a`，死区 `D(T_a)=T_a/f_c`。在 `D(T_a)+Q_α < B` 约束下取最小 C；若不可行，则必须走 per-step + 异步流水或 I10'。

### 0.2 伪力残差与意图

本体状态 `s_t`（关节 7+7+夹爪，或 ee 6+6+夹爪），已执行目标 `a_{t−1}`：

```
ŝ_t = s_{t−1} + clip(a_{t−1} − s_{t−1}, ±v_max·Δt)      # 无外力预测
r_t = s_t − ŝ_t                                          # 动作-观测残差
d_t = sqrt(r_t^T Σ_nom^{-1} r_t)                         # Mahalanobis 伪力
I_t = sign(Φ(s_t) − Φ(ŝ_t))                              # 进度势意图
```

- `Σ_nom` 由标称 episode 的残差协方差标定；阈值 `τ = sqrt(χ²_{dim,0.99})`，另设滞回带防抖。
- `Φ` 复用 I5 的官方得分点进度头（每任务满分 100）；`I_t>0` 表示人的位移把状态推向更高得分点（协助），`I_t<0` 为阻碍。
- 关节空间与 ee 空间分别标定；30fps 训练轨迹先降采样到 15Hz 再算差分（F26）。

### 0.3 人机干扰四模式分类

| 模式 | 视觉签名 | 残差 d_t | 进度势 I_t | 响应 |
|---|---|---|---|---|
| M1 穿越/遮挡 | 手可见、物体未动 | 小 | ≈0 | 预测碰撞则减速/停，否则继续 |
| M2 物体位移 | 物体位姿变、手离开 | 小 | <0 | 重定位（I9 检索）+ 重规划 |
| M3 物理推挤 | 手/身体接触、机器人被推动 | 大 | 可能<0 | 沿伪力方向让位/后退，再重规划 |
| M4 递物/协助 | 手携物靠近夹爪并停留 | 小或中 | >0 | 开夹爪、对准、接收、继续 |

M1 是“空间占用”，M2 是“世界状态变”，M3 是“本体被施加外力”，M4 是“人的意图是合作”。四者的响应不同，统一“检测到就停”会同时损失 M1 的效率与 M4 的得分。

### 0.4 多端口风险感知调度

N 端口共享 backend（F20），目标不是平均吞吐，而是：

```
min  Q_{0.99}(L)
s.t. J = Q_{0.99}(L) − Q_{0.5}(L) ≤ J_max        # 抖动（F23 可信度）
     S(actions) ≤ S_max                          # 动作平滑/健康度
     per-port state isolation                    # reset/历史不串
```

风险分 `ρ_i = w1·proximity(hand_i) + w2·d_t,i + w3·(1−slack_i)`。调度用 EDF + 风险破平；高风险端口独占“快车道”，低风险端口才允许短窗合批（`w_max≈10ms`）。过载时低风险端口复用上一 chunk/增大块长并做速度钳制，高风险端口保 deadline。

## 1. 创新点详述

### I10 双速率反应时架构 ★★★★★（新）
- **动机**：人类干扰占 20% 评测（F25），而默认块长 16@15Hz 造成 >1s 反应死区（F12/F22）。感知再好，反应时不够就必然碰撞或错过协助。
- **与现有方案差异**：多数队伍做“手部检测 + 停”，没有把反应时当约束；本点把 VLA 的慢规划与安全/协作的快反射解耦，并用 `L_r<B` 做准入门槛（PR6）。
- **技术可行性**：高。快反射是同一 VLA 的辅助头（共享视觉 encoder，输出 hold/yield/accept 三分类 + 速度缩放），不引入第二个决策模型（PR7）；推理侧用生产者-消费者异步流水，`get_action` 只读缓冲。
- **所需资源**：辅助头训练 1×24GB GPU·日；工程 2 人周；不增加推理 GPU。
- **落地步骤**：①书面确认 F22 块语义与 N；②按 §0.1 选 T_a（per-chunk 取 1–2；per-step 取 4–8 并异步）；③反射头离线训练；④本地 stub 测 L_r/p99/抖动；⑤单任务通道 M1–M4 真机抽测。
- **降级预案 I10'**：若“辅助头”被裁定为第二模型，改为规则安全滤波（速度钳制 + 距离阈值 + 停持）+ 短 chunk，不阻塞主链。
- **风险**：块语义若为开环，快反射在块内无法生效（见 §6 最大风险）；反射头误报导致频繁停机会拉低步骤分（缓解：滞回 + 仅在置信高时抢占）。

### I11 伪力残差 + 人机意图分类 ★★★★（新）
- **动机**：无触觉/力通道（F8），但接触与协助必须被识别；纯视觉在遮挡与身体接触时不可靠。
- **与现有方案差异**：把“命令-观测差”当作免费伪力通道；用官方得分点进度势 Φ 区分协助/阻碍，而不是把所有外力当危险。
- **技术可行性**：中-高。残差是纯计算（<1ms）；分类器可用轻量 MLP/树模型，输入为 `d_t`、残差方向、手 bbox、Φ 变化；标定数据来自 32 任务标称 episode + I5 合成扰动。
- **所需资源**：标定与训练 3 GPU·日；1 人周。
- **落地步骤**：①32 任务标称残差分布；②I5 合成 M2/M3/M4 片段并打标；③训练四分类 + 意图符号；④与 I4 状态机联调；⑤L0 AUROC/FPR，L2 真机确认。
- **风险**：机器人自身跟踪误差与外力混淆（缓解：按动作速度分层标定，高速段放宽阈值）；M4 递物与 M2 物体位移视觉相似（缓解：结合手-物-夹爪三者相对运动 + Φ 符号）。

### I12 风险感知多端口调度 ★★★★（新）
- **动机**：N 台真机并发（F20），共享 backend 的排队会放大尾延迟与抖动；而抖动本身影响可信度（F23）。
- **与现有方案差异**：常规做法是 FIFO/固定 batch；本点按“人类风险”分配算力，并把抖动作为一等约束，而不是只看均值。
- **技术可行性**：高。纯 CPU/服务层调度；模型侧只需支持动态 batch 与 per-port KV/历史隔离。
- **所需资源**：1 人周；无需额外 GPU。
- **落地步骤**：①埋点每端口 deadline/risk；②EDF+风险破平；③短窗合批与快车道；④N=3–5 压测 p99/抖动；⑤过载降级策略联调。
- **风险**：风险分误判导致算力错配（缓解：风险分只用可观测项 + 保守阈值）；合批增加单请求延迟（缓解：`w_max` 上限 + 高风险不合批）。

### I4 v3 人手干预门控（升级）
- 由 I11 的 `m_t` 驱动，不再“一律停”：M1 减速/绕行，M2 重定位，M3 让位/后退，M4 接收；停持仍是兜底。
- 保留 `obs_delta_indices` 历史栈做 <50ms 判别；干预态短 chunk、稳定态长 chunk 的旧策略改为“由调度器按风险分配”，因为 `action_chunk_size` 握手固定（F22），不能再逐 episode 改。

### I6 v2 低延迟部署服务（升级）
- 共享 backend + 每端口独立队列/状态（F20）；p99 目标由 §0.1 的 B 反推：B=100ms 时 p99<40ms、抖动 J<15ms。
- 复用官方 msgpack/websocket；`image_resize` 压带宽；异步生产者-消费者；动作健康度与延迟稳定性同时门禁（PR4 + F23）。
- 量化/CUDA Graph/torch.compile 保留；但任何优化都必须通过“延迟分布形状”验收，不只看均值。

### I8 v3 评测运营闭环（升级）
- 分级消融保留 L0/L1/L2；新增实时/交互指标：`L_r p50/p99`、抖动、M1–M4 分类准确率、恢复成功率、碰撞率。
- 注册表新增“离线反应时预测 vs 真机干扰得分”对齐；相关性 >0.6 才允许用离线指标单独准入 L2。
- 首批 L2 队列改为：①I10 反应时基线（T_a 扫描）→ ②I11 M1–M4 分类 → ③I4 v3 响应 → ④I12 N 端口压测。

### I1/I2/I3/I5/I7/I9（维持 + 本轮接口）
- **I1**：考纲五轴增广不变；新增“人为干扰”轴的合成只做训练增广，不做评测期适应。
- **I2**：新增 F26 对齐项——训练相机键/视角与评测键不同、30fps→15Hz 降采样，需在 loader 中显式重映射；否则共训收益会被输入域差吃掉。
- **I3**：接触段几何伺服与 I11 分工——I3 管“已知接触任务的精细对准”，I11 管“未知外力/全身扰动”。
- **I5**：合成示教新增“人类干扰”片段（虚拟手遮挡/推挤/递物），为 I11 提供标签；仍用官方得分点过滤。
- **I7**：世界模型前瞻与实时预算冲突加剧（O(1–2) 次 rollout 难进 100ms），维持待裁撤。
- **I9**：reset 检索在 M2 物体位移后触发“重检索”，为 I11 提供重定位先验。

```python
class DualRatePolicy:                          # 唯一参赛实体
    def __init__(self):
        self.vla   = load_vla()
        self.reflex = self.vla.aux_head("reflex")   # 同权重/同 encoder
        self.buf   = ActionBuffer()
        self.pool  = ThreadPoolExecutor(1)          # 异步生产者
        self.state = EpisodeState()

    def reset(self):
        self.buf.clear(); self.state.reset(); self.prior = None

    def get_action(self, obs):
        s = obs_state(obs)
        r, d = contact_residual(s, self.state.prev_s, self.state.prev_a)
        intent = sign(progress_head(s) - progress_head(self.state.pred_s))
        mode = classify(obs, d, intent)             # M1..M4

        if mode == "M3":                            # 物理推挤：让位优先
            return self.safe_yield(obs, r)
        if mode == "M4":                            # 递物：接收
            return self.accept_handover(obs)
        if mode == "M2":                            # 物体位移：重定位
            self.prior = self.retrieve(obs)         # I9
        if self.buf.low():
            self.pool.submit(self._produce, obs)    # 异步算下一块
        chunk = self.buf.get_or(self.vla.last_chunk)
        return self.shape(chunk, mode)              # 平滑/限速/裁剪

    def _produce(self, obs):
        with deadline(self.budget):                 # 超时则返回安全回退
            self.buf.put(self.vla.propose_chunk(obs, prior=self.prior))
```

### 2.2 伪力残差 + 意图

```python
def contact_residual(s, s_prev, a_prev, dt, v_max, Sigma):
    s_hat = s_prev + np.clip(a_prev - s_prev, -v_max*dt, v_max*dt)
    r = s - s_hat
    d = float(np.sqrt(r @ np.linalg.solve(Sigma, r)))   # Mahalanobis
    return r, d

def classify(obs, d, intent, hand):
    if d > TAU_HI and intent <= 0:      return "M3"     # 外力 + 阻碍
    if d > TAU_HI and intent >  0:      return "M4"     # 外力 + 协助
    if hand and not object_moved(obs):  return "M1"     # 手在但物未动
    if object_moved(obs):               return "M2"     # 物动、手离
    return "NONE"
```

### 2.3 风险感知调度

```python
def schedule(jobs, now):
    jobs.sort(key=lambda j: (j.deadline, -j.risk))      # EDF + 风险破平
    batch = []
    for j in jobs:
        if j.risk > RHO_HI:                             # 高风险：独占快车道
            run_alone(j); continue
        if not batch or j.deadline - now > W_MAX:
            batch.append(j)                             # 有松弛才合批
        else:
            run_batch(batch); batch = [j]
    run_batch(batch)
    # 过载：低风险端口复用上一 chunk + 速度钳制；高风险端口保 deadline
```
