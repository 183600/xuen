# 第 13 轮（新灵感循环第 1 轮）· ARGUS：动作条件化的视觉异常护栏——不把「没见过」当异常，只把「和我刚做的动作对不上」当异常

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新灵感循环第 1 轮，研究线承接第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO。三个灵感词是「视觉感知」「异常检测」「VLA」。本轮不推倒 CHUNK-SERVO 的 30 步规划 + 5 步伺服，而是补上它默认掉的一层：**在执行之前，先判断这只眼睛、这条残差、这个动作还值不值得信。**

## 0. 先给结论：CHUNK-SERVO 解决了「何时修」，没解决「该不该信」

第 12 轮的判断是对的：30 步开环 chunk 是接触精度的结构性弱点；把 30 步切成 6 个 5 步执行块，用演示检索的相对目标做视觉伺服，能把反馈周期从 1 秒压到 167 毫秒。但它默认了两个强假设：

1. **视觉观测是可信的**：腕部/头部图像没有遮挡、模糊、双目失配、标定漂移；看到的偏移就是真实的偏移。
2. **残差都是目标误差**：只要 `e(t)` 不为零，就加大伺服修正；修正方向由目标位姿决定。

在自由空间里，这两个假设基本成立；在接触、滑移、人为干扰和传感器失效时，它们会把机器人推向错误方向：

- **感知失效**：腕部被夹爪/物体遮挡，双目视差不可靠，或相机外参漂移。CHUNK-SERVO 仍然把噪声当目标，越修越偏。
- **执行异常**：孔壁顶住夹爪、物体在夹爪里滑动、机器人撞到桌面。CHUNK-SERVO 看到「偏了」，继续加大修正；正确反应可能是柔顺、退让、重抓，而不是硬修。
- **环境异常**：人把杯子挪走、把网口转了个角度。CHUNK-SERVO 的编辑检测能发现「场景动了」，但它没有校准的误报预算，也没有「让行」与「重定位」的明确分工。
- **任务异常**：目标不可达、物体拿错、相位判断错。继续伺服只会浪费 180 秒。

所以本轮的核心判断是：

> **执行层的下一个瓶颈，不是「修得更快」，而是「先判断这次观测和这条残差是否还值得信，再决定修、让、退、重规划还是降级」。**

但这里有一个本赛题特有的陷阱：

> **不能把「没见过」当异常。** 挑战赛的 5 类泛化轴里，位置、干扰物、桌面背景、未见物品、人为干扰，本来就会让场景外观偏离训练分布。一个通用的 OOD/novelty 检测器会在这些轴上疯狂误报，而它们恰恰是拿分点。

所以本轮押注 **ARGUS**：

> **ARGUS = Action-conditioned Residual Guard for Unreliable Sensing。用机器人自己的动作去预测「下一步应该看到什么」，只把「和这个预测对不上」的视觉/本体残差当异常；用保形 e-value 控制误报，用 CUSUM 做提前降速，用四类归因决定修/让/退/重规划/降级。VLA 仍是唯一学习模型；ARGUS 是确定性护栏，不是第二个模型。**

一句话：**不检测「陌生」，只检测「不一致」；不追求「更灵敏」，只追求「误报有预算、干预有上界、恢复能终止」。**

三个可验证创新点：

1. **AC-VAD（动作条件化视觉异常检测）**：用已知 EE/腰部运动和相机几何把上一帧 warp 到当前视角，用 URDF 自模型掩掉机器人自身，用双目一致性/跨视角一致性/本体跟踪残差/夹爪滑移残差做多通道证据。外观新颖本身不触发报警；只有「运动/几何/传感一致性被破坏」才触发。用 G2/G3 验证它是否真的对未见物品/背景不误报。
2. **保形 e-value + CUSUM 的双层报警**：每个任务/相位用成功演示和基线成功 rollout 做 Mondrian 保形校准；硬报警用 conformal test martingale 保证任意时刻误报 ≤ δ；CUSUM 只做 caution 和预失效降速，不单独触发硬恢复。用 G1/G2 验证误报率、检测延迟和 benign novelty 误报。
3. **异常门控执行 + 有界恢复**：伺服权限 α_k 随异常证据单调下降，修正量有硬上界；按感知/执行/环境/任务四类归因选择降级、柔顺、让行、重规划；恢复有最大次数/最大让行时间/安静窗口，保证终止。用 G4/G5 验证恢复是否真的涨点，而不是只涨 AUROC。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **视觉感知** | 头部双目一致性、腕部动作条件 warp、URDF 自模型掩码、跨视角一致性；双目只做一致性与粗定位，最后 1–2mm 仍靠腕部 IBVS | 不假设 API 有 depth；不把双目吹成毫米级；不做第二个视觉编码器 |
| **异常检测** | AC-VAD 多通道残差；Mondrian 保形 p/e-value；CUSUM caution；四类归因 | 不做通用 OOD/novelty 检测；不把「没见过」当异常；不训练异常检测网络 |
| **VLA** | VLA 仍是唯一学习策略；ARGUS 只门控伺服权限、触发重规划、给离线微调提供 near-miss 权重；VLA 动作分歧只做 caution | 不加载第二个策略/残差网络；不让异常检测器直接出动作；不把高分歧直接当异常 |

本轮**不重新抓取官网**，避免把旧事实包装成新事实。赛事事实、API、数据规模、WLA 基线、榜单取证均沿用第 12 轮已核验记录（检索日期 2026-10-28，证据等级 A/B）。本轮只新增两类信息：

1. **相关工作核对（2026-10-31，A 级：论文存在与摘要）**：RC-NF（CVPR 2026，arXiv:2603.11106）用 robot-conditioned normalizing flow 做 VLA 运行时异常检测，公开摘要称 100ms 内检测并触发 replan/rollback；ReconVLA（arXiv:2604.16677）用 conformal prediction 做状态级失败检测；通用装配异常检测（arXiv:2509.26308）在力/力矩时间序列上 AUROC >0.96。它们证明「运行时异常检测 + VLA 干预」是活跃方向，但也暴露了本赛题的空位：RC-NF 需要训练一个 normalizing flow（第二个学习模型），ReconVLA 主要看状态分布而非动作条件化的视觉一致性，力/力矩在本 API 里没有。

## 2. 诊断：三个「信任盲区」

把 CHUNK-SERVO 的一次修正拆开：

```text
t0: 观测 o_t → 目标检索/位姿估计 → 伺服误差 e_t → 修正 Δ_t
      ↑ 这里假设：o_t 可信、目标位姿可信、e_t 的方向可信
t0+167ms: 执行 5 步 → 新观测 o_{t+1}
      ↑ 这里假设：这 5 步没有发生滑移/碰撞/遮挡/人为移动
```

三个盲区：

1. **感知盲区**：双目失配、腕部遮挡、曝光/模糊、标定漂移。此时 `e_t` 是噪声，不是误差。
2. **归因盲区**：残差可能来自目标估计错、机器人跟踪错、物体滑移、人移动了物体、或者任务相位错。CHUNK-SERVO 主要把它们都解释成「目标估计有偏差」。
3. **误报盲区**：第 11 轮的 `edit_score` 是一个连续分数，没有按任务/相位校准的误报预算。阈值低一点，机器人频繁停在无关变化上；阈值高一点，真正的滑移/遮挡被放过。320 trials 的评测噪声约 2.4pp，不能靠手调阈值碰运气。

ARGUS 的切入点就是这三个盲区：**用动作条件化预测把「感知」变成可检验的假设；用保形校准把「误报」变成有预算的统计量；用四类归因把「残差」变成有区别的响应。**

## 3. 直觉：机器人自己知道「应该看到什么」

以 HangCup 为例：

- 机器人夹住杯子，腕部相机看到杯口和杯架。EE 从 `T_t` 移动到 `T_{t+1}`，相机跟着移动。即使不知道杯子的 3D 模型，**腕部图像的运动应该由 EE 运动解释**：背景按视差移动，夹住的杯子相对夹爪基本不动。
- 如果杯子在夹爪里滑了 2mm，腕部图像里杯子相对夹爪动了，但 EE 运动解释不了这部分运动 → **执行异常（滑移）**。
- 如果人把杯架挪了 5cm，头部双目里杯架的运动不由机器人动作解释 → **环境异常（人为干扰）**。
- 如果腕部被夹爪挡住一半，双目/跨视角一致性下降，但图像仍然「看起来正常」→ **感知异常（遮挡）**。
- 如果桌面换成了没见过的木纹、杯子换成了没见过的颜色，但机器人一动，图像运动仍然符合 EE 运动 → **不是异常**，VLA 应该继续做。

这就是「动作条件化」的核心：**H0 不是「这个场景我见过」，而是「这个场景的运动能用我刚做的动作解释」。** 前者会把泛化轴当异常，后者不会。

## 4. 方法总览：ARGUS 的三层

```text
┌────────────────────────────────────────────────────────────┐
│ 第 12 轮 CHUNK-SERVO：30 步 VLA 规划 + 5 步伺服执行          │
│   目标：T_base_target(t) · T_target_ee*；修正：K_p e + K_d ė │
└───────────────────────────┬────────────────────────────────┘
                            │ 每个 5 步 chunk 边界
                            ▼
┌────────────────────────────────────────────────────────────┐
│ ARGUS 监控层（CPU，确定性，无学习权重）                       │
│  C1 动作条件 warp：I_{k-1} → \hat I_k（头部/腕部）            │
│  C2 双目一致性；C3 跨视角一致性；C4 本体跟踪残差               │
│  C5 夹爪滑移；C6 任务进度停滞；C7 可选 latent novelty（诊断）  │
│      ↓                                                      │
│  Mondrian 保形 p-value → e-value → martingale 硬报警          │
│  CUSUM → caution → 预失效降速                                 │
│      ↓                                                      │
│  四类归因：感知 / 执行 / 环境 / 任务                           │
└───────────────────────────┬────────────────────────────────┘
                            │ 模式 + 权限 α_k
                            ▼
┌────────────────────────────────────────────────────────────┐
│ 执行层：SERVO / CAUTION / PERCEPT_FALLBACK / COMPLY /       │
│         YIELD / REPLAN / HOLD / SAFE_ABORT                  │
│  α_k ∈ [0,1] 单调门控；Δ 有界；恢复有次数/时间上界            │
└────────────────────────────────────────────────────────────┘
```

三个设计原则：

1. **只检测一致性，不检测熟悉度**：外观新颖不报警；动作解释不了的运动才报警。
2. **误报有预算**：硬报警用 conformal test martingale，任意时刻误报 ≤ δ；caution 只降速，不硬停。
3. **干预有上界**：伺服修正被 α_k 和 `δ_p/δ_r` 双重限幅；恢复最多 R 次；看不到目标就回退 VLA 开环，不硬做。

## 7. 一句话押注

**用机器人自己的动作预测「应该看到什么」，用保形 e-value 把误报关进预算，用 CUSUM 在硬报警前降速，用四类归因决定修/让/退/重规划/降级——VLA 仍是唯一学习模型，ARGUS 只做确定性护栏。**

**当前方案最大的风险：保形校准的交换性在跨机器人、跨光照、跨物体和人为干扰下不成立；一旦误报失控，机器人会被自己的护栏冻结，而漏报又会放过滑移——这是本轮的单点风险。**

| 项 | 约束 | 对 ARGUS 的含义 |
|---|---|---|
| 模型 | 所有任务须基于**同一模型**；不得混合多个模型 | ARGUS 必须是确定性控制器/统计层，不能是第二个学习模型 |
| 任务/次数 | 32 任务 × 10 次；5 类泛化各 2 次（位置/干扰物/背景/未见物品/人为干扰） | 异常检测必须在「未见物品/背景」上低误报；人为干扰轴是恢复的主战场 |
| 时限 | 单次真机 ≤180s | 恢复必须有时间上界；不能无限重试 |
| 部署 | N 台机器人，8765 起 N 个连续端口；每端口独立 reset | monitor 必须每端口独立、CPU 轻量、状态隔离 |
| 观测 | 四路 RGB 480×640；双臂关节/EE/夹爪/lower_body/语言 | 有头双目和腕部；无 depth/force/tactile |
| 动作 | `joint` 或 `ee` 互斥；`action_chunk_size` 固定；chunk 内无新观测、无打断 | monitor 只在 chunk 边界运行；不能假设 30Hz 反馈 |
| 数据 | 33,276 eps / 169.28h / 32 任务；头双目有内参/基线，腕部无内参 | 用成功演示做正常校准；腕部标定是 G0 |
| WLA | 6B；默认 chunk 30 @30Hz；24GB 可微调 action head | VLA 规划保持 30 步；ARGUS 只门控执行 |

### 1.2 相关工作（A：论文存在与摘要；数值仅作定位）

| 工作 | 做法 | 与本方案的区别 |
|---|---|---|
| **RC-NF**（CVPR 2026，arXiv:2603.11106） | Robot-conditioned normalizing flow，用机器人状态和物体轨迹做无监督异常检测；公开摘要称 100ms 内检测并触发 replan/rollback | 需要训练一个 normalizing flow，属第二个学习模型；本赛题单模型规则下有合规风险；没有动作条件化的几何 warp 和保形误报保证 |
| **ReconVLA**（arXiv:2604.16677） | 用 conformal prediction 做状态级失败检测；不重训 VLA | 主要看状态分布，不看动作条件化的视觉一致性；没有四类归因和有界恢复 |
| **通用装配异常检测**（arXiv:2509.26308） | 力/力矩时间序列 AD，公开摘要称 cabling/screwing AUROC >0.96 | 本 API 没有力/力矩；只能做视觉/本体 |
| **Conformal CUSUM / Conformal Test Martingale**（Vovk et al. 2025；Volkhonskiy et al. 2017） | 用保形 p/e-value 做变点检测，控制误报 | 本报告把它们接到「动作条件化多通道异常证据」上 |
| **D²-VLA**（arXiv:2609.34792） | 双记忆双频 VLA，提升动态长程操作 | 模型层创新；ARGUS 是执行层护栏，可叠加 |
| **RTC**（arXiv:2506.07339） | 异步执行 action chunk，降低推理延迟 | 解决吞吐/延迟；ARGUS 解决「该不该信、该不该修」 |
| **第 12 轮 CHUNK-SERVO** | 30 步规划 + 5 步视觉伺服 + 演示检索相对目标 | ARGUS 保留其伺服，增加感知可靠性门控与异常恢复 |

### 1.3 这些工作留下的空位

1. **单模型合规的空位**：RC-NF 这类学习型 monitor 效果好，但在「所有任务基于同一模型」的规则下容易被判为第二个模型。需要一个无学习权重、可解释、CPU 轻量的 monitor。
2. **动作条件化的空位**：多数异常检测问「这个状态是否在训练分布内」；本赛题真正要问「这个观测是否能用我刚做的动作解释」。前者会在未见物品/背景上误报，后者不会。
3. **误报预算的空位**：手调 `edit_score` 阈值没有统计保证；320 trials 的噪声约 2.4pp，不能靠调参碰运气。需要 anytime-valid 的误报控制。
4. **恢复闭环的空位**：检测到异常不等于会恢复。需要按类型选择降级/柔顺/让行/重规划，并且有次数/时间上界。

### 1.4 未核实/未解决

- 线上 `cam_left_high`/`cam_right_high` 是否与数据集 `head_stereo` 同一对、是否已校正；必须用单任务通道验证。
- 线上腕部相机内参是否可临时标定；数据集没有内参。
- 评测端实际控制频率（本报告假设 30Hz）和 RTT 分布。
- 人为干扰的具体协议：何时介入、是否允许接触机器人、是否会把物体拿走。
- 是否允许多次提交；单任务通道的调用配额。
- 官方对「模型」的解释是否覆盖「确定性统计 monitor」；本报告按 C2 合规设计，但需邮件确认。
- 真实失败分布；本报告没有失败演示，异常检测只能用合成扰动和成功数据校准。

## 2. 问题形式化

### 2.1 接口与时间模型

设：

- `f_c`：evaluator 控制频率（假设 30Hz）；
- `H`：提交的 `action_chunk_size`（本报告固定 5）；
- `τ`：网络 RTT + 图像传输 + VLA 推理的等效延迟；
- `B_mon`：monitor 单 chunk 预算（目标 ≤10ms）；
- `T_fb`：从世界变化到策略看到变化的反馈周期。

```math
T_{\mathrm{fb}} \approx \frac{H}{f_c} + \tau.
```

| 场景 | `H` | `f_c` | `τ` | `T_fb` | 评价 |
|---|---:|---:|---:|---:|---|
| 官方 WLA 默认 | 30 | 30 | 50ms | 1050ms | 接触段基本开环 |
| CHUNK-SERVO | 5 | 30 | 50ms | 217ms | 可做 1–2 次接触修正 |
| ARGUS 低延迟 | 5 | 30 | 20ms | 187ms | monitor 需 ≤10ms |
| ARGUS 高延迟 | 5 | 30 | 150ms | 317ms | 降增益，monitor 只做 caution |
| 低控制频率 | 5 | 10 | 50ms | 550ms | 只做 PBVS/降级，不追 IBVS |

**结论**：ARGUS 的监控频率与 chunk 绑定；chunk 大小仍是提交前要扫的超参数，不能在线改变。ARGUS 在线改变的是「伺服权限、模式、是否重规划」，不是 `action_chunk_size`。

### 2.2 动作条件化零假设

在 chunk `k` 边界，观测：

```math
o_k = \left(I^{h,L}_k, I^{h,R}_k, I^{w,L}_k, I^{w,R}_k, s_k\right),
```

其中 `s_k` 包含双臂 EE 位姿、夹爪、`lower_body`。上一段命令：

```math
a_{k-1} = \{(T^{ee,L}_{k-1,j}, T^{ee,R}_{k-1,j}, g_{k-1,j})\}_{j=0}^{H-1}.
```

由正运动学/标定得到相机位姿 `T^{cam}_k`；由双目或平面先验得到深度代理 `D_k`。定义**动作条件预测算子**：

```math
\hat{o}_k = \mathcal{P}\left(o_{k-1}, a_{k-1}; \Theta_{\mathrm{robot}}, \Theta_{\mathrm{calib}}\right),
```

其中 `Θ_robot` 是 URDF/运动学，`Θ_calib` 是相机内外参。零假设：

```math
H_0:\quad o_k = \hat{o}_k + \varepsilon_k,\quad
\varepsilon_k \sim \mathcal{N}_{\mathrm{cal}},
```

即「当前观测可以由上一帧、已知动作、刚体附着假设和传感器健康解释」。备择假设：

```math
H_1:\quad \exists\, e_k \notin \mathcal{E}_{\mathrm{model}}
\ \text{s.t.}\ o_k \neq \mathcal{P}(o_{k-1},a_{k-1}) + \varepsilon_k,
```

其中 `e_k` 是未建模事件：人移动物体、物体滑移、碰撞、遮挡、相机故障、任务相位错。

**关键点**：`H_0` 不要求场景外观熟悉。一个没见过的杯子，只要它的运动能被机器人动作解释，就仍在 `H_0` 下。这样把「泛化轴」和「异常」分开了。

### 2.3 异常类型

把通道分成四组：

| 组 | 通道 | 典型事件 | 是否动作条件化 |
|---|---|---|---|
| `G_perc` | C2 双目一致性、C3 跨视角一致性、C8 图像质量 | 遮挡、模糊、曝光、双目失配、标定漂移 | 否（传感器健康） |
| `G_exec` | C4 本体跟踪残差、C5 夹爪滑移、C6 任务停滞 | 碰撞、卡住、滑移、抓空 | 是（动作/夹爪条件） |
| `G_env` | C1 头部/腕部动作 warp 残差 | 人移动物体、物体被拿走、背景大改动 | 是（动作条件） |
| `G_task` | C7 进度停滞、C9 语义新颖性（可选） | 目标不可达、拿错物体、任务误解 | 部分 |

类型判定：

```math
g_k = \arg\max_{g\in\{\mathrm{perc},\mathrm{exec},\mathrm{env},\mathrm{task}\}}
w_g \cdot \max_{j\in G_g} z_{k,j},
```

若 `max_j z_{k,j} < τ_type`，则 `g_k = unknown`。`w_g` 是代价权重（默认全 1，可按任务调）。

### 2.4 决策目标

每个 chunk 选择模式 `m_k ∈ M` 和伺服权限 `α_k ∈ [0,1]`：

```math
\max_{m,\alpha}\ \mathbb{E}\left[
\Delta \mathrm{progress} - \lambda_{\mathrm{risk}} R(m) - \lambda_{\mathrm{time}} T(m)
\;\middle|\; \mathcal{H}_k
\right]
```

约束：

```math
\mathbb{P}(\text{false alarm at any }k) \le \delta,\qquad
\|\Delta a\| \le \delta_p,\qquad
\|\Delta r\| \le \delta_r.
```

由于 `E[·]` 不可靠估计，在线用**字典序**近似：

1. 先满足硬报警的误报约束（martingale）；
2. 再看异常类型，选择最小风险的响应；
3. 最后在安全响应集合内保留尽可能多的 VLA 前馈。

这不是一个在线优化器，而是一个**风险约束下的确定性策略**。

### 2.5 可辨识性条件

视觉异常通道只在以下条件满足时启用：

1. 目标/受器在至少一个视野内；
2. 双目 ROI 有效像素 ≥70%，或腕部特征 inlier ≥15；
3. 相机标定误差在门限内（重投影 ≤5px）；
4. 动作 warp 的深度代理有效（双目深度或平面先验）；
5. 任务/相位属于刚体接触类；变形任务只启用 C4/C5/C8，不启用 C1。

任一条不满足 → 关闭对应通道，降低 `α_k`，但不硬停；monitor 不能因为一个通道失效就整体失效。

## 3. ARGUS 算法

### 3.1 总体架构

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / 5-step action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port ARGUS PolicyService (CPU)  │
                    │  ├─ CHUNK-SERVO (round 12)          │
                    │  ├─ AC-VAD monitor (this round)     │
                    │  ├─ conformal + CUSUM + martingale  │
                    │  ├─ mode/recovery state machine     │
                    │  └─ action adapter (WLA 54D → API)  │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared VLA server (GPU)            │
                    │  UnifoLM-WLA-1.0 / VLA-0, 30-step   │
                    └─────────────────────────────────────┘
```

- 每个端口一个 monitor 实例，独立校准表/状态/CUSUM。
- 校准表只读、可共享（copy-on-write），内存 <50MB/端口。
- VLA 请求异步；monitor 不阻塞 `get_action`；monitor 超时则降级到 3 通道。

### 3.2 符号表

| 符号 | 含义 |
|---|---|
| `k` | chunk 索引，`t_k = kH/f_c` |
| `H` | 提交的 action chunk 大小，固定 5 |
| `o_k` | 第 k 个 chunk 边界的观测 |
| `a_{k-1}` | 上一段命令（绝对 EE 位姿 + gripper + pivot） |
| `T^{ee}_k`, `T^{cam}_k` | EE/相机在 base 系的位姿 |
| `\mathcal{P}` | 动作条件预测算子（warp/自模型/深度代理） |
| `s_{k,j}` | 第 j 个通道的非一致性分数 |
| `p_{k,j}` | Mondrian 保形 p-value |
| `e_{k,j}` | 保形 e-value，`κ_j p_{k,j}^{κ_j-1}` |
| `e_k` | 多通道平均 e-value |
| `M_k` | 测试鞅，`∏_{i≤k} e_i`；`L_k = log M_k` |
| `z_{k,j}` | 惊讶度，`-\log p_{k,j}`，可截断 |
| `S_{k,j}` | CUSUM 统计量 |
| `h_{c,j}` | caution 阈值 |
| `ν_j` | CUSUM 漂移项 |
| `α_k` | 伺服权限 ∈[0,1] |
| `Δ_k` | 伺服修正（EE 局部系 6D） |
| `δ_p`, `δ_r` | 每 chunk 最大平移/旋转修正 |
| `ρ_k` | 感知可靠度 ∈[0,1] |
| `g_k` | 异常类型 |
| `R` | 最大恢复次数（默认 2） |
| `T_yield` | 最大让行时间（默认 5s） |
| `W_q` | 安静窗口（默认 3 chunks） |

### 3.3 离线校准

**输入**：

- 32 任务成功演示（33,276 eps；按 session/物体/背景分组划分）；
- 可选的基线 VLA 成功 rollout（同一任务/初始条件；用于匹配测试动作分布）；
- 相位标签（第 10 轮 FACT-VLA 的 CPT；或第 11 轮几何相位）；
- 相机标定/腕部标定（G0）。

**步骤**：

1. 对每个任务 `t`、相位 `φ` 建立分层 `(t,φ)`；样本不足时退到任务级。
2. 回放演示/成功 rollout，计算每个 chunk 的通道分数 `s_{k,j}`。动作条件通道用**该轨迹实际执行的动作**做预测；这样 `H_0` 与测试时一致。
3. 对每个通道做稳健归一化：

```math
\tilde{s}_{k,j} = \frac{s_{k,j} - \mathrm{median}_{cal}(s_{\cdot,j})}
{\mathrm{MAD}_{cal}(s_{\cdot,j}) + \epsilon}.
```

4. 排序保存 `\tilde{s}_{\cdot,j}`，用于在线二分查找 p-value。
5. 在留出的正常序列上校准 CUSUM：`ν_j = mean_normal(z_{k,j}) + margin`，`h_{c,j}` 取使 caution 频率约为 1/50 chunks 的分位数；`z_{k,j}` 截断到 `z_max`。
6. 选 `κ_j = 0.5`，`δ = 0.05`（可调）；`M_0 = 1`。
7. 在**未见物品/背景**的留出集上验证误报；若 benign novelty 误报 >10%，去掉 C9/C7 等外观敏感通道，或提高 `δ`。
8. 可选：计算 near-miss 权重，供 VLA action-head 微调使用（§5.7）。

**重要**：如果只有演示、没有基线 VLA 成功 rollout，测试时的动作分布可能和演示不同，导致 `p` 偏小。此时对分数乘一个保守膨胀因子 `γ_cal > 1`（例如 1.2），并在单任务通道重新校准。

### 3.4 在线通道

#### C1 动作条件 warp

头部相机：

- 由 `state_d435` / `lower_body` 恢复 `T^{cam}_k`；
- 用双目视差得到 `D_{k-1}`；
- 对上一帧做逆 warp：

```math
\hat{I}_k(u) = I_{k-1}\left(\pi\left(K T^{cam}_{k-1} (T^{cam}_k)^{-1} K^{-1} \tilde{u} D_k(u)\right)\right).
```

- 用 URDF 在当前关节角下渲染机器人自模型掩码 `M^{self}_k`，膨胀 5px，排除机器人像素；
- 残差：

```math
r^{warp}_k = \mathrm{median}_{u\in\Omega_k}
\frac{|I_k(u) - \hat{I}_k(u)|}{|\nabla I_k(u)| + \epsilon}.
```

腕部相机：

- 由 EE 位姿 + 手眼标定得到 `T^{wrist}_k`；
- 深度代理：头部双目投影到腕部 ROI，或目标距离处的局部平面；
- 同样的 warp；若腕部无内参，关闭 C1 腕部，只保留 C5 滑移；
- 固定夹爪掩码，排除夹爪像素。

#### C2 双目一致性

- 校正后，对左图 ROI 的每个像素在右图对应极线上搜索视差 `d∈[0,D]`；
- 计算最佳匹配代价 `c(u)`、唯一性约束、左右一致性；
- 定义有效比例 `ρ^{stereo}_k = |\{u: valid\}|/|\Omega|`；
- 残差 `r^{stereo}_k = median(c(u)/|\nabla I(u)|)`；
- `ρ^{stereo}_k < 0.7` 或残差高 → 感知异常候选。

#### C3 跨视角一致性

- 仅在腕部内参/手眼标定通过 G0 时启用；
- 用头部双目 + 第 11 轮几何估计目标/受器位姿 `T^{h}_{target}`；
- 投影到腕部相机，与腕部检测到的目标特征比较；
- `r^{cross}_k =` 重投影误差（px）；inlier 比例作为置信度；
- 两个视角对同一个目标给出矛盾位姿 → 感知异常候选。

#### C4 本体跟踪残差

- 上一 chunk 最后一个命令位姿 `T^{cmd}_{k-1,H-1}`；
- 当前观测 EE 位姿 `T^{obs}_k`；
- `r^{prop}_k = ||\log((T^{obs}_k)^{-1} T^{cmd}_{k-1,H-1})||_\Sigma`（平移 mm + 旋转 rad 加权）；
- 用相位条件校准，区分「正常接触柔顺」与「碰撞/卡住」。

#### C5 夹爪滑移

- 夹爪闭合时，在腕部 ROI 跟踪物体特征；
- 由于夹爪与相机刚性连接，物体若刚性附着，特征在腕部图像中应基本不动；
- `r^{slip}_k = median` 特征位移（px 或经深度换算的 mm）；
- 夹爪打开时禁用；抓空时用 C4/C6 兜底。

#### C6 任务进度停滞

- 用相位/距离目标的进度代理 `prog_k`；
- 若连续 `W_stall` 个 chunk 无进展且不在接触段，`r^{stall}_k = 1`；
- 离散通道，单独用一个小 p-value 表校准。

#### C7 可选 latent novelty

- 用同一 VLA checkpoint 的视觉 encoder 特征，计算到校准集的 Mahalanobis/kNN 距离；
- **只做诊断**，不直接触发硬报警；用于人工分析和离线数据筛选；
- 若官方对单模型解释严格，默认关闭。

#### C8 图像质量

- 拉普拉斯方差（模糊）、过曝/欠曝比例、帧间直方图突变；
- 作为 `ρ_k` 的乘子，不单独报警（除非极端）。

#### C9 语义新颖性

- 可选；用 VLA 语言-视觉相似度或 latent；只用于 `G_task` 诊断；
- 不在未见物品/背景轴上触发恢复，避免把泛化当异常。

#### C10 可选：VLA 动作分歧（只做 caution）

WLA 的 action head 是扩散式的；在必要时采样 `K` 个 action chunk（不同噪声种子），计算两两分歧：

```math
r^{vla}_k = \frac{1}{\binom{K}{2}}
\sum_{i<j} \left\|a^{(i)}_k - a^{(j)}_k\right\|_\Sigma.
```

- 高分歧表示 VLA 自己对动作不确定；但它也可能是「没见过但正确」的泛化，所以**只做 caution**：降低 `α_k`、提前刷新计划，不触发硬恢复。
- 默认 `K=1`（关闭）；只在 `CAUTION` 或计划过期时采样 `K=3`，避免推理开销。
- 不与 C7/C9 同时默认开启，避免「泛化轴误报」叠加。

### 3.5 保形 e-value 与 CUSUM

#### 保形 p-value

对每个分层 `(t,φ)` 和通道 `j`：

```math
p_{k,j} = \frac{1 + \#\{i \in \mathcal{D}_{cal}(t,\phi): \tilde{s}_{i,j} \ge \tilde{s}_{k,j}\}}
{n_{t,\phi} + 1}.
```

在交换性下，`P(p_{k,j} ≤ α) ≤ α`。

#### 保形 e-value

取 `κ_j ∈ (0,1)`（默认 0.5）：

```math
e_{k,j} = \kappa_j\, p_{k,j}^{\kappa_j-1},\qquad
e_k = \frac{1}{J}\sum_{j=1}^J e_{k,j}.
```

若 `p_{k,j}` 是超均匀的，则 `E[e_{k,j}] ≤ 1`（证明见 §4.1）。`e_k` 也是 e-value。

#### 硬报警：conformal test martingale

```math
M_k = \prod_{i=1}^k e_i,\qquad
L_k = L_{k-1} + \log e_k,\qquad
\text{alarm if } L_k \ge \log(1/\delta).
```

在 `H_0` 下，`M_k` 是非负超级鞅；Ville 不等式给出：

```math
\mathbb{P}\left(\exists k: M_k \ge 1/\delta\right) \le \delta.
```

这是**任意时刻**的误报控制，不依赖 episode 长度，不需要 Bonferroni 过 K 个 chunk。

**恢复后的重置**：每次硬报警进入恢复、并返回 `SERVO` 时，重置 `M_k=1`、`L_k=0`、`S_k=0`，把之后视为一个新的测试段。为了保持整 episode 的误报预算，按最多 `S_max` 段分摊（默认 `S_max=4`）：

```math
\delta_{\mathrm{seg}} = \frac{\delta}{S_{\max}},
\qquad
\text{alarm if } L_k \ge \log(1/\delta_{\mathrm{seg}}).
```

这是 union bound；比不重置更保守。若不允许重置，`M_k` 会一直带着之前的证据，恢复后容易反复报警；工程上不可取。段数 `S_max` 与连续尝试次数 `R` 分开：`R` 限制同一异常的最多重试，`S_max` 限制整个 episode 的硬报警段数。

#### Caution：CUSUM

```math
z_{k,j} = \min\left(-\log p_{k,j},\ z_{\max}\right),
```

```math
S_{k,j} = \max\left(0,\ S_{k-1,j} + z_{k,j} - \nu_j\right),
```

```math
\text{caution if } \max_j S_{k,j} > h_{c,j}.
```

CUSUM 只做 caution：降低 `α_k`、提前刷新 VLA 计划、降速；不单独触发硬恢复。这样即使 CUSUM 阈值没调好，也不会破坏硬报警的误报保证。

#### 为什么两层

- **硬报警**要的是「不能经常误停」：martingale 给 anytime-valid 保证。
- **caution**要的是「早一点降速」：CUSUM 对持续小异常更敏感，且即使误报也只是降速，不是硬停。
- 两者互补：martingale 可能对 `p` 在 0.05–0.2 的弱异常反应慢；CUSUM 会先进入 caution，给机器人争取时间。

### 3.6 异常归因与响应

| 类型 | 证据签名 | 第一响应 | 恢复 | 失败回退 |
|---|---|---|---|---|
| `perc` | C2/C3/C8 高；C1 可能也高 | `PERCEPT_FALLBACK`：切到可靠视角（腕部坏→头双目 PBVS；头部坏→腕部 IBVS；两者都坏→VLA 开环）；降速 0.5× | 换视角/重新标定检查 | 仍无效 → `HOLD` + `REPLAN` |
| `exec` | C4/C5/C6 高 | `COMPLY`：沿接触法向退 1–2mm；滑移则闭合夹爪/重抓；卡住则回撤重进 | 最多 R 次；每次降低速度 | 超限 → `SAFE_ABORT` 或 `REPLAN` |
| `env` | C1 头部/腕部高；C2/C3 正常 | `YIELD`：若检测到人手/移动物体，先停/回撤到安全位；若人接触被夹物体，优先松开夹爪让行；否则保持夹持等待 `T_yield` | 人离开后重定位目标；物体移动则更新 goal | 目标消失 → `REPLAN` |
| `task` | C6/C7/C9 高 | `REPLAN`：用当前观测请求新 VLA 计划 | 最多 1 次重规划；仍无进展 → `SAFE_ABORT` | 不硬做 |
| `unknown` | 无组超过阈值但 martingale 报警 | `HOLD` + `REPLAN` | 保守处理 | 超限 → `SAFE_ABORT` |

**通道活动性**：感知通道是否参与硬报警取决于当前伺服模式。若当前只用腕部 IBVS，头部双目失效（C2/C3）只作为诊断/低权重，不应单独硬停；反之亦然。只有「当前模式依赖的视角失效」才触发 `perc` 硬恢复。这个规则避免「一个无关视角坏了，机器人却停住」。

**让行原则**：如果机器人手里拿着物体，不轻易张爪；先保持夹持、回撤、等待。只有在确认物体已掉落/抓空且安全时，才重抓。

### 3.7 伺服权限与预失效降速

定义综合惊讶度：

```math
z_k = \max_j z_{k,j}.
```

取正常校准的 95% 分位 `z_0` 和 99.9% 分位 `z_1`：

```math
\alpha_k = \mathrm{clip}\left(
\frac{z_1 - z_k}{z_1 - z_0},\ 0,\ 1
\right)\cdot \rho_k.
```

- `z_k ≤ z_0` → `α_k = ρ_k`（正常，最多 1）；
- `z_k ≥ z_1` → `α_k = 0`（完全回退 VLA 前馈）；
- 中间线性下降。

注意：`ρ_k` 是**当前伺服模式实际使用的视角**的可靠度，不是所有视角的全局最小。PBVS 用头部双目可靠度，IBVS 用腕部 inlier 可靠度，混合模式取加权平均；否则一个无关视角失效会把伺服整体关掉。

伺服修正：

```math
\Delta_k = \alpha_k \cdot \mathrm{clip}\left(
K_p e_k + K_d \dot{e}_k,\ \pm\delta_p,\ \pm\delta_r
\right).
```

性质：

- `α_k ∈ [0,1]`，`Δ_k` 有界；
- `α_k` 随 `z_k` 单调不增；
- `α_k = 0` 时命令等于 VLA 前馈（或恢复动作），不会产生额外偏差；
- caution 时 `α_k` 降低、速度乘 `γ=0.5`、提前刷新计划，但不硬停。

class ARGUSPolicy:
    def __init__(self, vla, servo, monitor, adapter, token):
        self.vla = vla
        self.servo = servo
        self.monitor = monitor
        self.adapter = adapter
        self.token = token
        self.state = "INIT"
        self.plan = None
        self.plan_idx = 0
        self.future = None
        self.last_cmd = None
        self.attempts = 0
        self.segments = 0
        self.in_recovery = False
        self.yield_t0 = None
        self.quiet = 0
        self.R = 2
        self.S_max = 4
        self.W_q = 3
        self.task = None
        self.phase = "unknown"
        self.executor = ThreadPoolExecutor(max_workers=1)

    def get_action(self, obs):
        if self.state == "INIT":
            self._reset_episode(obs)

        # 1) monitor: action-conditioned evidence at chunk boundary
        ev = self.monitor.update(obs, self.last_cmd, self.task, self.phase)

        # 2) hard alarm / caution / state machine
        self._update_state(ev, obs)

        # 3) async VLA plan refresh (never blocks)
        self._maybe_request_plan(obs)

        # 4) compose 5-step action chunk
        a_cmd = self._compose_action(obs, ev)

        # 5) API adapter: WLA 54D -> challenge 21D absolute EE
        out = self.adapter.to_api(a_cmd, obs, self.token)
        self.last_cmd = out
        return out

    def _update_state(self, ev, obs):
        if ev.hard_alarm:
            if not self.in_recovery:
                self.segments += 1
                self.in_recovery = True
            self.state = self._triage(ev)   # PERCEPT_FALLBACK/COMPLY/YIELD/REPLAN/HOLD
            self.attempts += 1
            self.quiet = 0
            if self.attempts > self.R or self.segments > self.S_max:
                self.state = "SAFE_ABORT"
        elif ev.caution:
            if self.state == "SERVO":
                self.state = "CAUTION"
            self.quiet = 0
        elif self.state == "CAUTION":
            self.quiet += 1
            if self.quiet >= self.W_q:
                self.state = "SERVO"
        elif self.state in ("PERCEPT_FALLBACK", "COMPLY", "YIELD", "REPLAN"):
            if ev.recovered:
                self.state = "SERVO"
                self.attempts = 0
                self.in_recovery = False
                self.monitor.reset_test_segment(self.delta / self.S_max)
        elif self.state == "HOLD":
            self.state = "REPLAN"

    def _compose_action(self, obs, ev):
        if self.state in ("PERCEPT_FALLBACK", "COMPLY", "YIELD", "REPLAN", "HOLD"):
            return self._recovery_chunk(obs, self.state)

        plan = self.plan
        if plan is None:
            return self._safe_hold_chunk(obs)

        a_ff = plan[self.plan_idx : self.plan_idx + self.H]
        if self.state == "SERVO" and self.servo.goal is not None:
            e = self.servo.error(obs, self.servo.goal)
            delta = self.servo.correction(e, ev.alpha)
            a_cmd = compose_relative(a_ff, delta)
        else:
            a_cmd = a_ff

        self.plan_idx += self.H
        if self.plan_idx >= len(plan):
            self.plan = None
        return a_cmd

    def _maybe_request_plan(self, obs):
        if self.future is not None and not self.future.done():
            return
        if self.future is not None:
            self.plan = self.future.result()
            self.plan_idx = 0
            self.future = None
        if self.plan is None or self.state in ("REPLAN", "CAUTION"):
            snapshot = copy_obs(obs)
            self.future = self.executor.submit(self.vla.predict, snapshot)

### 3.10 与 VLA 的接口

- **唯一学习策略**：VLA 仍是唯一输出动作的模型；ARGUS 不改 VLA 权重，不加载第二个策略。
- **门控**：ARGUS 只乘伺服修正 `Δ`，不覆盖 VLA 前馈；硬报警时进入确定性恢复动作。
- **重规划**：`A_task`/`A_env` 时请求新 VLA 计划；请求异步，失败则用旧计划 + 保守权限。
- **离线 near-miss 加权**：见 §5.7；只改 action-head 微调的样本权重，不新增模型。
- **合规**：monitor 默认只用确定性几何/统计；可选 latent 通道用同一 checkpoint 特征，且默认关闭。

## 4. 理论分析

### 4.1 误报控制

**引理 1（e-value 的有效性）**。设 `p` 是超均匀 p-value（`P(p≤t)≤t`），`κ∈(0,1)`，`e(p)=κ p^{κ-1}`，则 `E[e(p)]≤1`。

证明：用生存函数积分。

```math
\mathbb{E}[e(p)] = \int_0^\infty \mathbb{P}(e(p)>t)\,dt.
```

对 `t>0`：

```math
e(p)>t \iff p < (\kappa/t)^{1/(1-\kappa)}.
```

因此

```math
\mathbb{P}(e>t) \le \min\left(1, (\kappa/t)^{1/(1-\kappa)}\right).
```

令 `a=1/(1-κ)>1`，则

```math
\mathbb{E}[e] \le \kappa + \int_{\kappa}^{\infty} (\kappa/t)^a dt
= \kappa + (1-\kappa) = 1.
```

**定理 1（任意时刻误报控制）**。若每个 `p_{k,j}` 在给定历史下条件超均匀，则 `M_k=∏_{i≤k} e_i` 是非负超级鞅，且

```math
\mathbb{P}\left(\sup_k M_k \ge 1/\delta\right) \le \delta.
```

证明：`E[e_k|F_{k-1}] ≤ 1`，故 `E[M_k|F_{k-1}] ≤ M_{k-1}`；由 Ville 不等式得证。

**边界**：

- 保形 p-value 只保证边际有效性；条件有效性需要 Mondrian/分层交换性。本报告按任务/相位/机器人分层，尽量接近条件有效。
- 时间序列相邻帧不独立；用 episode 级/块级校准和留出验证降低依赖。若交换性严重破裂，`δ` 保证不严格成立；此时以单任务通道的实测误报为准。
- 离散 p-value 使 e-value 偏保守（实际 `E[e]≤1`），不会提高误报。
- 多段重置：每段用 `δ_seg=δ/S_max`，整 episode 误报 ≤δ（union bound）；`S_max` 是最大硬报警段数（默认 4），`R` 是同一异常的最大连续重试次数（默认 2）。超过 `S_max` 进入 `SAFE_ABORT`，不再报警。

### 4.2 干预有界性

**命题 2**。对任意 chunk，`α_k∈[0,1]`，`||Δ_k||≤δ_p`，`||Δr_k||≤δ_r`；若 `α_k=0`，则 `a_cmd=a_ff`。且 `α_k` 对 `z_k` 单调不增。

证明：由 `clip` 和 `α_k` 定义直接得到；`z_k` 增大时分子 `z_1-z_k` 减小，`α_k` 不增。

**推论**：ARGUS 不会让动作偏离 VLA 前馈超过 `δ_p/δ_r`；最坏情况是回退到 VLA 开环，即第 12 轮基线。因此 ARGUS 的「干预风险」有上界，但不是「任务成功率有下界」——恢复动作仍可能失败。

### 4.3 检测延迟

**命题 3**。若在 `k_0` 之后每个 chunk 的 `e_k ≥ e_min > 1`，则硬报警最晚在

```math
k_0 + \left\lceil
\frac{\log(1/\delta) - L_{k_0-1}}{\log e_{\min}}
\right\rceil
```

个 chunk 内触发。

证明：`L_k ≥ L_{k_0-1} + (k-k_0+1)\log e_min`；令其 ≥`log(1/δ)` 解出。

对 `κ=0.5`、`p=α`：

```math
e_{\min} = 0.5/\sqrt{\alpha}.
```

| `α` | `e_min` | `log e_min` | `δ=0.05` 时最坏延迟（chunks） | 时间 @30Hz, H=5 |
|---:|---:|---:|---:|---:|
| 0.10 | 1.581 | 0.458 | 7 | 1.17s |
| 0.05 | 2.236 | 0.805 | 4 | 0.67s |
| 0.01 | 5.000 | 1.609 | 2 | 0.33s |

这是「持续证据」的最坏情况；如果 `p` 在 0.05–0.2 波动，martingale 会慢，CUSUM caution 会先触发降速。不要把这个表当成真实检测延迟；真实延迟由 G2 实测。

### 4.4 恢复终止性

**命题 4**。在有限 episode（≤180s）内，恢复状态机不会无限循环。

证明：定义 ranking 函数

```math
\Phi = (R - \mathrm{attempts}) + (S_{\max} - \mathrm{segments})
+ \frac{T_{\max} - t_{\mathrm{elapsed}}}{T_{\max}}.
```

每次进入新的恢复段，`segments` 增加；每次重试，`attempts` 增加；`YIELD`/`HOLD`/`REPLAN` 消耗 `t_elapsed`。`attempts > R`、`segments > S_max` 或 `t_elapsed > T_max` 时进入 `SAFE_ABORT`；`YIELD` 有 `T_yield` 上界；`HOLD` 只持续 1 个 chunk；`REPLAN` 最多 1 次。因此 `Φ` 单调下降，状态机在有限步内进入 `DONE`/`SAFE_ABORT`。

### 4.5 复杂度

设：

- `N`：monitor ROI 像素数（默认 160×120=19,200）；
- `D`：双目视差搜索范围（默认 32）；
- `F`：稀疏特征数（默认 64）；
- `W`：跟踪窗口（默认 15）；
- `L`：金字塔层数（默认 3）；
- `J`：通道数（默认 6）；
- `n_cal`：每层校准样本数（≤10,000）。

| 步骤 | 复杂度 | 19,200 px 的粗略量级 |
|---|---|---:|
| 降采样/灰度 | `O(N)` | 0.02M |
| 双目块匹配 | `O(N D)` | 0.61M |
| 动作 warp | `O(N)` | 0.02M |
| 光度残差 | `O(N)` | 0.02M |
| 稀疏光流 | `O(F W^2 L)` | 0.04M |
| 保形 p-value | `O(J log n_cal)` | 可忽略 |
| CUSUM/martingale | `O(J)` | 可忽略 |
| 决策/状态机 | `O(J + 模式数)` | 可忽略 |
| **合计** | `O(N D + F W^2 L + J log n_cal)` | **<1M 次基本运算** |

- 优化 C++/NumPy 下 <5ms/chunk；Python 纯循环可能 10–20ms。目标 `B_mon ≤10ms`，用 ROI + 降采样 + 向量化。
- 内存：`O(N + F + J n_cal)`，校准表 <5MB/通道，总 <50MB/端口；无额外模型权重。
- 离线校准：18.28M 帧，若每 3 帧取 1 帧、每帧 1ms，约 1.7h/通道；可并行/抽样。实际只对 A 档 19 任务和接触相位做全量，B 档抽样。

### 4.6 正确性边界

- 保证只覆盖「`H_0` 下误报」；不保证「`H_1` 下一定检测」。视觉不可见的异常（夹爪内部打滑但物体纹理不变、力过大但无法观测）可能漏检。
- 不保证恢复成功；恢复是确定性规则，必须过 G4/G5。
- 不保证跨机器人/跨光照的交换性；需要每机器人/每批次重校准。
- 不是安全证书；碰撞避免仍靠限速、限幅、最大尝试次数和人工监督。

## 5. 视觉感知前端细节

### 5.1 头部双目

- 数据集 `head_stereo` 有内参、畸变、R/T、基线 58.2526mm、`rectified: true`；线上 `cam_left_high`/`cam_right_high` 是否同一对、是否已校正，必须 G0 验证。
- 深度误差：

```math
\delta z \approx \frac{z^2}{f b}\,\delta d.
```

以 `f≈282px`、`b≈58.25mm`：

| 距离 | 视差 | `δd=0.1px` 的深度误差 | `δd=0.5px` 的深度误差 |
|---:|---:|---:|---:|
| 0.5m | 32.9px | 1.5mm | 7.6mm |
| 0.75m | 21.9px | 3.4mm | 17.1mm |
| 1.0m | 16.4px | 6.1mm | 30.4mm |

**对第 12 轮的一个修正**：第 12 轮说头双目在 0.5–1.0m 上「足够局部毫米级深度」，这偏乐观。只有亚像素视差（≤0.1px）且近距离时才是毫米级；1m 处 0.1px 也有 6mm。因此本报告把双目定位为**一致性检查 + 粗定位**，最后 1–2mm 仍靠腕部 IBVS/目标图。异常检测不需要毫米级深度，只需要「视差是否一致」。

### 5.2 腕部相机

- 数据集腕部 `camera_params` 只有 `color/ir1/ir2`，没有内参矩阵；必须一次性标定（棋盘格/已知 EE 运动），或用 D435 先验 + 头部双目投影。
- 若标定失败：关闭 C1 腕部，只保留 C5 滑移（不需要内参：物体相对夹爪的特征位移）和 C8 图像质量。
- 眼在手外参：`T^{wrist} = T^{ee} · T_{handeye}`；用 EE 运动预测腕部图像运动。深度代理用头部双目投影到腕部 ROI，或目标距离处的局部平面。

### 5.3 自模型掩码

- 用 G1 URDF + 当前关节角渲染头部相机中的机器人掩码；膨胀 5px；排除机器人像素。
- 腕部用固定夹爪掩码（夹爪相对相机静止）；膨胀 3px。
- 掩码误差会导致边缘残差；用梯度加权 + 鲁棒中位数抑制；若掩码覆盖率 <80%，降低 `ρ_k`。

### 5.4 动作条件 warp 的数值细节

- 逆 warp：对当前帧像素 `u`，用深度 `D_k(u)` 反投影到当前相机系，变换到上一帧相机系，投影到上一帧，双线性采样。这样输出与当前帧对齐，便于逐像素残差。
- 深度无效/遮挡：用前后向一致性检查；无效像素不参与中位数。
- 平面代理：若深度不可用，用目标距离 `z_0` 的局部平面，homography `H = K (R + t n^T/z_0) K^{-1}`；只对目标 ROI 使用。
- 梯度加权：`w(u)=1/(|\nabla I(u)|+ε)`，避免纹理空白区主导。
- 残差归一化：用校准集的 median/MAD，得到 `\tilde{s}`。

### 5.5 特征与残差

- 光度残差用灰度；滑移用 ORB/LK 稀疏特征；不要用需要第二个学习模型的描述子。
- 滑移特征只在物体 ROI 内；夹爪闭合才启用；特征数 <15 时降低置信度。
- 对透明/反光/变形物体：C1/C5 置信度低，回退 C2/C3/C4；不硬做。

### 5.6 置信度与退化

```math
\rho^{head}_k = \min\left(1,\frac{\rho^{stereo}_k}{0.7}\right)(1-\mathrm{blur}_k),
\qquad
\rho^{wrist}_k = \min\left(1,\frac{\rho^{inlier}_k}{0.5}\right)(1-\mathrm{blur}_k).
```

按当前伺服模式取：

```math
\rho_k =
\begin{cases}
\rho^{head}_k, & \text{PBVS / 头双目主导},\\
\rho^{wrist}_k, & \text{IBVS / 腕部主导},\\
\frac{w_h \rho^{head}_k + w_w \rho^{wrist}_k}{w_h+w_w}, & \text{混合}.
\end{cases}
```

- `ρ_k < 0.3`：视为感知异常，`α_k=0`，进入 `PERCEPT_FALLBACK`。
- 腕部未标定：`C1_wrist` 关闭，`C5` 保留；IBVS 不可用 → 只用 PBVS。
- 双目失效：`C1_head`/`C2`/`C3` 关闭，`C4`/`C5`/`C6` 保留；VLA 开环兜底。
- 变形任务（FoldTowel）：`C1` 关闭，只用 `C4`/`C5`/`C8`；ARGUS 主要防碰撞/卡住，不声称提升折叠精度。

### 5.7 离线 near-miss 加权（可选，给 VLA 微调）

成功演示里有一类「高异常但最终成功」的片段：接近碰撞、滑移后重抓、插入前多次微调。它们数量少，但正好是接触精度的信息富集区。均匀行为克隆会把它们和自由空间帧同等对待，导致最后 3 厘米欠拟合。

用 ARGUS 的异常分数给这些帧加权：

```math
w_i = 1 + \lambda \cdot \mathbb{1}\left[z_i \in [z_{0.90}, z_{0.99}]\right]
\cdot \mathbb{1}\left[\phi_i \in \{\text{pre-contact},\text{contact}\}\right],
```

或平滑版本：

```math
w_i = 1 + \lambda \exp\left(-\frac{(z_i-z_m)^2}{2\sigma^2}\right)
\cdot \mathbb{1}\left[\phi_i \in \{\text{pre-contact},\text{contact}\}\right].
```

约束：

- `z_i` 必须用**留一 session/物体**的校准表计算，避免样本在自己的校准集里；
- `w_i` 截断到 `w_max`（默认 3），并归一化到均值 1，保持有效学习率；
- 只在 action-head 微调时用，不改 VLM，不新增模型；
- 用留出任务验证；若无增益或回归，直接关掉。

损失：

```math
\mathcal{L} = \frac{\sum_i w_i\, \ell(\pi(o_i), a_i)}{\sum_i w_i}.
```

风险：高异常也可能是传感器噪声或罕见但错误的策略；`w_max` 和留出验证是必要的护栏。

## 6. 实验设计

### 6.1 离线

| 实验 | 数据 | 指标 | 门 |
|---|---|---|---|
| 保形覆盖 | 留出正常 episodes（按 session/物体/背景分组） | 经验误报 ≤δ+2%；分任务/相位不崩 | G1 |
| 异常可分 | 合成扰动 + 真实失败回放 | AUROC/AUPRC；分类型 | G2 |
| 检测延迟 | 持续异常注入 | 中位/p90 chunks | G2 |

合成异常注入：

1. 遮挡：随机黑块/前景物体遮住目标 ROI；

8. 碰撞/卡住：冻结 EE 或关节 1–3 chunks；
9. 帧丢失/延迟尖峰：重复上一帧/延迟 1–2 chunks。

## 7. 竞赛策略与预算

### 7.1 任务分档

沿用第 12 轮：

- **A 档（伺服优先，19 个）**：HangCup、DisconnectEthernet、ToolboxStorage、PlugCharger、Unlock、ArrangeTestTubes、OpenPillBottle、OrganizeStationery、PackBag、ZipUp、PaperCupStacking、StoreRacket、StackCups、PlugInEthernet、StackBowls、StoreEarphones、PackPhone、OrganizePencilCase、SyringeWaterTransfer。
- **B 档（VLA 优先，13 个）**：FruitCollection、PackDoll、FruitSorting、ColorArrangement、PlacePhotoFrame、OrganizeBookshelf、PickOutBatteries、OrganizeTools、FoldTowel、ArrangePlates、SpellRobot、ConveyorSorting、RemovePinnedNote。
- **C 档**：单任务通道里 `p_t` 接近 0 且失败在早期感知/抓取的任务；不投 ARGUS 工程。

ARGUS 的优先顺序：

```math
\mathrm{priority}_t = \frac{q_t \cdot \Delta_t^{\mathrm{ARGUS}}}{c_t},
```

`q_t` 是失败发生在「可观测异常」的比例；`Δ_t^{ARGUS}` 是恢复/防误动作的条件增益；`c_t` 是标定/调参成本。

### 7.2 预期收益（设计目标，不是承诺）

- 人为干扰轴占 20%；若恢复把 human 轴从 `p_h` 提到 `p_h+Δ_h`，全局 `+0.2Δ_h`。
- 若 ARGUS 在 10 个接触任务上各把成功率提高 5–10pp，全局约 `+10/32×5–10 = +1.6–3.1pp`。
- 若再避免 5 个误动作/碰撞任务各 +5pp，全局 `+0.8pp`。
- 保守合计 **+2–4pp**；乐观 **+5–6pp**。必须用配对 A/B 证明；320 trials 的 SE≈2.4pp，不能把 +1–2pp 当结论。

|---|---:|---|---|
| P0 基线/接口 | 1 周 | WLA + API adapter + CHUNK-SERVO 基线；腕部标定 | G0 |
| P1 离线 monitor | 2 周 | 通道实现；保形校准；离线评测 | G1/G2/G3 |
| P2 仿真恢复 | 2 周 | 异常注入；四类恢复；阈值/增益扫描 | G4/G6 |

- 1×24GB GPU：WLA 推理/action-head 微调；
- 16–32 CPU 核：monitor/校准/仿真；
- 存储：演示关键帧/校准分数 <10GB（不需要全视频缓存）。

### 7.4 最小可行版本（MVP）

不要第一周就实现全部通道。先做一个能证伪的 MVP：

1. **通道**：C2 双目有效比例、C4 本体跟踪残差、C5 夹爪滑移；不做 C1 warp/C3 跨视角。
2. **校准**：任务级（不分相位）Mondrian 保形 p-value；CUSUM caution；martingale 硬报警。
3. **模式**：`SERVO` / `CAUTION` / `PERCEPT_FALLBACK` / `COMPLY` / `SAFE_ABORT`；先不做 `YIELD`/`REPLAN`。
4. **任务**：HangCup（挂）和 PlugInEthernet（插）各 5 次 A/B；只回答「误报是否可控、滑移/卡住是否能提前降速」。
5. **通过后再加**：C1 动作 warp、C3 跨视角、`YIELD`/`REPLAN`、near-miss 加权。

MVP 的价值不是涨点，而是用最小成本验证三个致命问题：腕部/双目是否可用、保形误报是否可控、恢复是否比不恢复更安全。

### 8.3 安全

- 所有修正限幅；`α_k` 门控；恢复最大 R 次。
- 让行时保持夹持、回撤、等待；不轻易张爪。
- `SAFE_ABORT` 回安全位，不继续追目标。
- 人为干扰轴：不声称 100% 检测；人进入视野时优先安全。

| 第 13 轮 ARGUS | AC-VAD、保形 e-value、CUSUM caution、四类归因、有界恢复 | 本报告 | 不做通用 OOD；不训练异常网络 |

**保留**：官方 WLA 基座、33k 演示、单任务通道、仿真标定。
**升级**：感知可信度 → 统计证据；固定权限 → 门控权限；单一恢复 → 分类恢复。
**剪枝**：通用 novelty、学习型 monitor、30Hz 全通道、力/触觉、异常检测直接出动作。

## 11. 一句话押注与最大风险

**押注：用机器人自己的动作预测「应该看到什么」，用保形 e-value 把误报关进预算，用 CUSUM 在硬报警前降速，用四类归因决定修/让/退/重规划/降级——VLA 仍是唯一学习模型，ARGUS 只做确定性护栏。**

**当前方案最大的风险：保形校准的交换性在跨机器人、跨光照、跨物体和人为干扰下不成立；一旦误报失控，机器人会被自己的护栏冻结，而漏报又会放过滑移——这是本轮的单点风险。**
