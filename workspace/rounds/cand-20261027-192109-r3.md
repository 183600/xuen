# 第 9 轮（灵感循环第 3 轮）· COTE-SURE：把预算从训练搬到推理

> 检索/复核日期：2026-10-27（UTC）。赛事身份确认不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。文件内上一轮是第 8 轮 SURE-BT；本轮不是推倒重来，而是给它补上“低成本验证”和“推理时执行”两条腿。三个灵感词是「低成本方案」「评测基准」「原型验证」。我先核实赛事与数据，再把三个词钉到本轮新增的硬事实上，最后合成主判断：**在 30% 天花板下，最便宜、最可能立刻见效的创新不是再训一个更大的 VLA，而是把算力搬到推理时——用重叠动作块集成（COTE）降低开环 chunk 的复合误差，并把集成残差当作免费的 surprise 信号驱动 SURE-BT 的验证/恢复；用四层回放基准（TRB）在真机前筛掉坏主意；用两周、一张 24GB 卡的原型验证决定是否押注。**

## 0. 本轮先核实：六个事实与两个纠正

### 0.1 榜单仍是占位，29.7% 不是真实头部

我先把 `leaderboard_data.json`、榜单页、详情页三处对齐：

- JSON 仍写着 `generated_from: "gen_leaderboard.py"`，8 个模型 × 32 任务 = 256 条 `task_metrics`，发布时间 2026-10-08（[S9]）。
- 榜单页有 8/8 条记录，但底部仍是“即将发布”，首页排行榜也是“即将发布”（[S8]）。
- 详情页每个任务都写“测试视频占位，后续可替换为真实视频文件”（[S10]）；`runs.html` 是 256/256 占位（[S11]）。

所以本轮继续把 29.7% 当作**难度先验**，不当真实排名证据。更不能从占位数据推断“哪个轴最弱”“哪个队最强”。这是本轮所有预算讨论的前提。

### 0.2 N 端口从“未核实”变成官方硬约束

第 8 轮把“N 端口并发”标为社区观察、未核实。本轮提交模板 [S7] 明确：

> Evaluation runs across **N test robots** in randomized order (the exact N is announced separately by the organisers), and the evaluator connects to one fixed port per robot. A submission must expose **N consecutive ports** starting at `8765` (`8765`, `8766`, …, `8765 + N − 1`); the number of exposed ports must exactly match the number of robots N, and each port must independently and reliably complete the entire interaction flow of its robot.

这带来三条硬约束：

1. **端口数必须恰好等于 N**，多开少开都不行；N 未公布，原型要按 N=1/2/3/4 做容量规划。
2. **每个端口对应一台机器人、一个 episode**，`reset()`、历史、COTE 缓冲、BT 状态、谓词状态都必须 per-port 隔离。
3. 官方给了两种部署方式：N 个独立进程（N 份模型副本）或共享后端 + 请求分发；后者要处理并发与状态隔离。

这条纠正直接推翻“先随便起一个 8765 就行”的工程假设。低成本的正确做法不是买 N 张卡，而是**一个共享模型后端 + N 个轻量端口 + 每端口状态机**，并把 p99 延迟纳入验收。

### 0.3 数据是 33,276 条 / 169.28h，不是 32,000

官网写“32,000 演示样本 / 169 小时”（[S1]），新闻稿也沿用 32,000（[S22]）。我逐仓读 `meta/info.json` 求和，实际是：

| 量 | 实际值 | 来源 |
|---|---:|---|
| episodes | **33,276** | 32 个 HF 数据仓逐仓求和（[S5][S24]） |
| frames | **18,282,246** | 同上 |
| 时长 | **169.28h @30fps** | 同上 |
| 每任务 episodes | 969–1,533 | 同上 |
| 相机 | head stereo ×2 + wrist ×2，640×480 | [S6] |
| 数据格式 | LeRobot v3.0 | [S6] |

32,000 是官网四舍五入/宣传口径，不是训练集真实规模。差别不大，但做数据预算时要用 33,276；做“5% 留出集”时是 1,664 条，不是 1,600 条。

### 0.4 官方底座可以在单张 24GB GPU 上低成本后训练

WLA-1.0-Base 于 2026-09-28 发布：6B、Apache-2.0、约 2,500h 真机数据、64 任务、支持二指夹爪与五指手（[S12]）。更关键的是官方训练文档 [S13] 和配置 [S14]：

- 默认微调配置面向 **单张 24GB GPU**；
- VLM backbone 冻结，只训 **action expert（DiT-L）+ robot-state projector**；
- `per_device_batch_size: 1`，`gradient_accumulation_steps: 8`，`max_train_steps: 20000`；
- 支持 LoRA：action model 的 attention 线性层，`r=16 / alpha=32`，VLM 也可选 LoRA；
- 原生 action horizon = **30**，action dim = **54**，diffusion 推理步数 = **4**；
- 动作表示：EE 与 base pose 是**相对当前状态的 SE(3) 变换**，其余动作保留原语义（[S15]）。

这意味着“低成本原型”不是空话：一张 4090/A5000/L4 级别的卡、几天到两周、官方数据的一个子集，就能跑一次 action-expert LoRA。真正的风险不是算力，而是**训了也不涨**——下一节的外部证据正好说明这一点。

### 0.5 任务元数据：2–5 步、12/12/8 难度、30/32 有人扰备注

我把 32 个 `info.json` 全抓了一遍（[S4]），得到本轮最有用的任务侧硬事实：

| 维度 | 分布 |
|---|---|
| 难度（官方） | Easy 12、Medium 12、Hard 8 |
| 评分步骤数 | 2 步 11 个、3 步 14 个、4 步 5 个、5 步 2 个 |
| 最后一步权重 | 50 分 11 个、40 分 14 个、25 分 5 个、20 分 2 个 |
| 人扰备注 | **30/32** 同时有 `human_1_note` 与 `human_4_note`；T31、T32 整个 `generalization` 字段缺失 |

T31（OrganizePencilCase）和 T32（SyringeWaterTransfer）没有官方人扰剧本，这是基准构造的缺口：不能假装官方备注覆盖全部任务，必须自己补两条剧本，并标为“我们的假设”。

另外，占位榜单里任务成功率与官方难度几乎不相关（Easy 26.1%、Medium 24.7%、Hard 24.6%），步骤分减成功率（gap）集中在 6.0–10.3pp。**如果这组占位数据有任何参考价值，它说明瓶颈不是“难任务不会”，而是“所有任务都在最后一段掉链子”。** 但这是合成数据，只能当假设，不能当结论。

### 0.6 外部证据：naive LoRA 可能负收益，推理时集成更划算

这是本轮最重要的外部信息，也是我把主火力从训练搬到推理的直接原因。

**负结果**：2026-10-01 发表在 Frontiers in Neurorobotics 的一项研究报告，SmolVLA + LoRA + 时序平滑正则 + chunk-aware 辅助监督，在 30,000 步预算下**没有提升**成功率；匹配的固定 chunk k=8 基线是 10.9%±1.1，加了 LoRA+平滑+辅助损失反而降到 3.5%±1.4%；平滑项把轨迹 jerk 提高到 1.69 RMS（基线 0.59）。同一篇论文里，**训练无关的推理时时序集成**（ACT 式重叠 chunk 平均）在两个 suite 上把成功率从 19.0%→36.2%、24.0%→56.2%，代价是 2.3× step-rate。作者结论很直白：在这套配置/预算/基准下，**推理时集成是同样算力更强的用法**（[S16]）。

**鲁棒性差异**：IndustrialVLA-Bench 在统一协议下比较 6 个 VLA/WAM，干净 LIBERO 平均只差 1.58 分，但鲁棒性、指令改写分别差 14.62、31.08 分（[S19]）。VLA-GAUGE 评估 12 个 VLA，平均零样本只有 22.3%，组合扰动下 R-Score 只有 9.3（[S18]）。

**轻量鲁棒模块**：StableVLA 的 IB-Adapter 用 <10M 参数、不要额外数据/增强，报告平均提升约 30% 的视觉扰动鲁棒性；0.5B backbone 的鲁棒性接近 7B VLA（[S17]）。这是一条可选架构线，但不是本轮主线。

**运行时包装**：Harness VLA 把冻结 VLA 当作可重试的接触-rich primitive，外面套解析 primitive 和 planner，在 LIBERO-Pro / RoboCasa365 上比最强基线高 38.6 / 27.1pp，真机展示抓取恢复（[S20]）。注意：它用的是 LLM coding agent 做 planner，这在 UniBot 的“单模型、不得混用”下大概率不合规；我们只用它的**思想**——冻结 VLA 负责局部接触，确定性代码负责重定位/重试/换序——而不是把 LLM 搬进运行时。

这三条证据合起来，支持一个反直觉的判断：**在 30% 天花板下，先别急着训；先把推理时的执行做对。**

## 1. 三个灵感词，钉到本轮事实上

### 1.1 低成本方案：不是“少训练”，而是“把训练换成推理”

我一开始把“低成本”理解成“用 LoRA 少训一点”。但负结果 [S16] 提醒我：**低成本训练也可能是负收益**；30k 步的 LoRA + 平滑正则，不仅没涨，还显著掉了。真正便宜的是**不改权重、只改推理时行为**的方法：重叠 chunk 集成、相位门控、安全端点、预测一致性检查。它们不需要新数据、不需要新 checkpoint、不需要重训，失败了可以一键回退。

所以本轮的“低成本”定义是：

- **数据成本**：0 条新真机数据；只用官方 33k；
- **算力成本**：1 张 24GB GPU 做推理/验证；训练只用于可选的谓词头或 IB-Adapter；
- **工程成本**：在现有 `PolicyService` 里加一个 per-port 的 COTE 缓冲和 BT tick，不改模型服务协议；
- **决策成本**：每个想法都有 1–2 周的 kill gate，失败就回退，不沉没。

“低成本”不是“便宜但没用”，而是**单位美元的信息增益最高**。这就是为什么我把 TRB 放进主线：它让每个想法在真机前就能被筛掉。

### 1.2 评测基准：TRB 是四层阶梯，不是另一个榜单

第 8 轮的 SMB-320 想复刻官方 32×10 矩阵，方向对，但成本还是偏高：真机、仿真、2.5D 编辑都要人。本轮把它改造成 **TRB（Tiered Replay Benchmark）**：

| 层 | 做什么 | 能回答什么 | 成本 |
|---|---|---|---|
| T0 | 官方留出 episode 的回放 | 动作误差、平滑度、谓词 F1 | CPU/1 卡，小时级 |
| T1 | 在留出帧上做 label-preserving 扰动 | 背景/干扰物/未见物/遮挡的鲁棒性 | 1 卡，天级 |
| T2 | 3 个刚体任务的 MuJoCo/Isaac 闭环 | COTE/BT 的闭环增益 | 1 卡，1–2 周 |
| T3 | 官方不计分单任务调试槽 | 真机失败模式、最终裁决 | 配额，稀缺 |

TRB 的定位不是“替代官方榜单”，而是**在花真机时间之前，把明显坏的主意杀掉**。它的核心指标是动作块差异（ACD）、终端加权 ACD（TW-ACD）、平滑度、surprise AUROC、谓词 F1、轴间 gap、p99 延迟。它不能证明成功率，只能证明“执行层有没有变好”；最终必须用 T3 校准。

### 1.3 原型验证：两周、一张卡、可证伪

本轮的原型不是“训一个模型看看”，而是**验证一个运行时假设**：

> 在相同的 WLA-1.0-Base 上，COTE 能否在不增加不可接受延迟的前提下，降低动作块差异/抖动，并让 SURE-BT 的边界恢复更及时？

两周计划：

- **D1–D2**：把相对 EE 动作积分成绝对位姿，回放 100 条官方 episode，验证积分误差 <1cm；跑通 N=1/2/3 端口与 token。
- **D3–D5**：实现 COTE-Free / COTE-2x；在 1,000 个留出锚点上测 ACD、jerk、p99。
- **D6–D9**：接 SURE-BT 谓词与 surprise；在 T1 扰动集上测 AUROC/F1。
- **D10–D12**：T2 三个刚体任务（StackBowls / StoreCups / HangCup）闭环；没有资产就跳过，不硬造孪生。
- **D13–D14**：官方调试槽 3 任务×10 次，COTE on/off 配对；决定是否进全量提交。

预算：1 张 24GB GPU（自有或按需，约 200–400 GPU-hours）、100GB–1TB 存储、2 人两周；不含机器人采购。按社区/云价粗算，现金成本 <$500；若用自有卡，接近 0。

## 2. 为什么把主火力从训练搬到推理

### 2.1 30% 天花板的算术

官方 320 个 episode（32×10），p≈0.3 时二项 SE≈2.56pp，95% CI 半宽≈±5.0pp；单轴 64 次，SE≈5.73pp；单任务 10 次，SE≈14.5pp。配对设计下，差值 SE≈sqrt(d/320)：d=0.15 → 2.17pp，d=0.20 → 2.50pp。**+3pp 只能算“可能有信号”，+5pp 才是稳妥目标。**

如果 COTE 的真实效应是 +3–5pp，320 次真机只能勉强分辨；3 任务×10 次的调试槽（30 次）根本不够。所以必须用 TRB 的大样本离线锚点做筛选，再用 320 次真机做确认。这个统计事实决定了本轮的方法论：**先离线大样本，后真机小样本。**

### 2.2 负结果：30k 步 LoRA 没赢，时序集成翻倍

[S16] 的数字很重要，我把它拆成三条：

1. **训练侧**：LoRA + 平滑 + chunk-aware 辅助损失，30k 步，四 suite 宏平均 3.5%±1.4，低于固定 chunk 基线 10.9%±1.1；Spatial −16.4pp（p=0.004）、Object −17.5pp（p=0.002）。
2. **推理侧**：训练无关的时序集成，Spatial 19.0→36.2%，Object 24.0→56.2%，代价 2.3× step-rate。
3. **结论**：在这套配置/预算/基准下，**推理时集成是同样算力更强的用法**。

这不是说“所有 LoRA 都没用”，而是说：**在底座已经见过任务、数据分布相同的条件下，低预算的 action-side 微调很可能打不过一个正确的推理时 wrapper。** UniBot 正好符合这个条件：WLA-1.0-Base 已经在 2,500h、64 任务上训过，UniBot 的 33k 又在同一数据生态里；再用同样的数据做普通微调，边际收益本来就应该低。

### 2.3 干净能力差异小，鲁棒性差异大

IndustrialVLA-Bench 的 1.58 vs 14.62/31.08 很有说服力：在干净 LIBERO 上，六个系统差不多；一到鲁棒性/指令改写，差距拉开一个数量级（[S19]）。VLA-GAUGE 的零样本 22.3%、组合扰动 R-Score 9.3 也说明：**现在的 VLA 不是“不会任务”，而是“一扰动就崩”**（[S18]）。

UniBot 的评分恰好是 5 类泛化各 20%，其中位置、干扰物、背景、未见物品、人扰——**80% 是视觉/场景/动态扰动，只有位置是纯几何**。这进一步支持“执行/鲁棒性”而不是“任务知识”是主战场。

### 2.4 底座已见过任务，gap 是执行

WLA-1.0-Base 的 64 任务、2,500h 覆盖了桌面操作；UniBot 的 32 任务数据也在官方生态里。虽然我不能证明底座一定见过这 32 个任务的正样本（模型卡没有逐任务列表），但“底座已经很强、微调边际收益低”是一个合理的先验。真正的 gap 是：

- chunk 内开环，遇到扰动不能中途改；
- 接触-rich 的插入/闭合/倾倒，位置误差几毫米就失败；
- 双手支撑手漂移；
- 背景/干扰物/未见物导致视觉表征漂移；
- 人扰发生在 chunk 中间，机器人到下一个边界才知道。

这些都不是“再训一个更大的模型”能直接解决的，而是**推理时验证/恢复**和**小 chunk 反应性**的问题。

### 2.5 结论：先推理，后训练

所以本轮的资源分配是：

- **70%**：COTE + SURE-BT + TRB（推理时/验证）；
- **20%**：工程（相对→绝对动作适配、N 端口、p99、状态隔离）；
- **10%**：可选轻量训练（谓词头、IB-Adapter、LPAA），且必须先过 TRB。

这不是放弃训练，而是把训练放到“已验证有 gap”的地方，而不是一上来就 20k 步 LoRA。

## 3. COTE：重叠动作块集成

### 3.1 问题：chunk 开环 + 固定 chunk

提交模板 [S7] 明确：`action_chunk_size` 是固定整数；`get_action` 返回 `(T_a, ...)`；评测端按 index 0..T_a−1 顺序执行，**执行完整个 chunk 才再次调用** `get_action`。这意味着：

- BT 只能在 chunk 边界 tick；
- 人扰/滑落发生在 chunk 中间时，机器人要到下一个边界才知道；
- chunk 越长，反应越慢；chunk 越短，推理越频繁、动作越容易抖。

主流 VLA（如 MolmoAct2）也承认一批 10–30 步执行期间不重规划。**这是结构性缺陷，不是某个模型的 bug。**

### 3.2 算法：COTE-Free 与 COTE-2x

COTE 的核心是：**每次调用不只返回当前 chunk，而是保留模型原生 30 步预测，与上一次预测在重叠区融合；执行融合后的前 L 步。**

两种模式：

| 模式 | `action_chunk_size` | 查询频率 | 额外推理 | 适用 |
|---|---:|---:|---:|---|
| COTE-Free | 8 | 3.75Hz | 0× | 延迟不够时；默认 |
| COTE-2x | 4 | 7.5Hz | 2× | p99 <133ms 时；反应性优先 |
| COTE-3x | 2–3 | 10–15Hz | 3–5× | 仅当模型极快；一般不推荐 |

关键点：模型的**原生 horizon 是 30**，但接口只要求返回 `T_a` 步。我们可以在服务端内部算 30 步，返回前 L 步；下一次调用时，上一次预测的后 30−L 步仍在缓冲里，可以和这次预测融合。**COTE-Free 不需要额外推理**，只是把模型已经算出来的未来用起来。

### 3.3 融合数学

设第 j 次调用在全局步 t_j，模型输出 30 步绝对目标 `A_j[0..29]`。缓冲区保存上一次的 `A_{j-1}` 和它的起始步 `t_{j-1}`。令 Δ = t_j − t_{j-1}（已执行的步数）。对 k=0..29：

```text
age = k + Δ
w_new = exp(-λ * age)
w_old = exp(-λ * k)          # 上一次预测中对应同一全局步的项
A_fused[k] = (w_new * A_j[k] + w_old * A_{j-1}[k + Δ]) / (w_new + w_old)
```

λ=0.10–0.20；Δ=4 时新预测权重约 0.55–0.60，Δ=8 时约 0.30–0.45。直觉：新预测更可信，但旧预测提供时间一致性。

分量处理：

- **平移**：线性加权平均；
- **旋转**：四元数 slerp 或旋转向量加权（不要直接平均 RPY，会有万向锁/绕回）；
- **关节**：关节空间线性平均（注意限位）；
- **夹爪**：不平均，取最新命令 + 迟滞（开/合阈值分开）；
- **腿/躯干**：默认取最新；只有稳定站立时才平均。

### 3.4 相位门控与发散门控

**相位门控**：BT 知道当前评分步骤 `step_id`；只在 `step_id` 不变时融合。谓词推进时清空缓冲，避免把“抓取”与“抬升”两个相位平均成犹豫。

**发散门控**：计算新预测与旧预测在重叠区的归一化差异

```text
d = median_k( || A_j[k] - A_{j-1}[k+Δ] || / scale )
```

若 `d > τ_d`（例如干净数据 95 分位的 2–3 倍），说明场景/相位发生了大变化，**只用新预测，清空缓冲**。这可以避免人扰后还把旧轨迹拉回来。

**安全端点**：返回 chunk 的最后一步做限速/限加速度；只有在不可逆步骤（插入/倾倒/闭合/堆叠终局）前才强制 hold。不要每个 chunk 都完全停，否则 180s 会被切碎。

### 3.5 免费 surprise：用集成残差驱动 SURE-BT

COTE 的 `d` 不只是融合权重，它还是一个**免费的 surprise 信号**：

- 如果 `d` 突然变大，且当前步骤谓词未完成 → 可能人扰/滑落/抓空/碰撞；
- 如果 `d` 变大，但谓词刚好完成 → 可能是正常相位切换；
- 如果 `d` 持续高 → `WaitClear` / `Regrasp` / `Reanchor`；
- 如果 `d` 低且谓词稳定 → `continue`。

这替代了第 8 轮的“风险头”（一个需要训练的辅助头）。**不需要额外模型、不需要标签、不需要训练**；代价只是几行代码。它也有失败模式：正常快速运动、遮挡、相机抖动都会让 `d` 变大；所以必须结合谓词、迟滞、几何校验。

### 3.6 小 chunk 的反应性红利

第 8 轮把 `action_chunk_size=8` 当默认，因为 16 太慢、4 太抖。COTE 改变了这个权衡：

- L=4 → BT tick 7.5Hz，反应性翻倍；
- COTE 在重叠区融合，抑制小 chunk 的抖动；
- 如果 p99 允许，**L=4 + COTE-2x 可能是比 L=8 更好的组合**：既快又稳。

这是本轮最具体的“低成本创新”：不换模型、不重训，只改 chunk 的返回方式，就把“反应性 vs 平滑性”的帕累托前沿往外推。

### 3.7 接口细节：相对→绝对动作适配

WLA 的 EE 动作是**相对当前状态的 SE(3) 变换**（[S15]），而提交 API 的 `action.*_ee_pose_gripper_base` 是**base 系绝对位姿**（[S7]）。所以服务端必须做积分：

```text
T_abs[0] = T_current * exp(Δξ_0)
T_abs[k] = T_abs[k-1] * exp(Δξ_k)
```

其中 `Δξ` 是模型输出的相对平移+旋转。做错这一步，机器人会“看起来在动但越走越偏”。原型第一件事就是用官方 episode 回放验证：把记录的动作积分回去，和记录的 EE 轨迹比，误差应 <1cm / <2°。这是比任何模型创新都优先的 unit test。

另外：

- `obs_delta_indices` 要与 WLA 训练配置对齐；不要凭猜；
- `image_resize` 先用原生 480×640，确认基线后再试 240×320 降延迟；
- `control_space` 选 `ee` 还是 `joint` 要与动作适配一致，不能混；
- 每端口独立 `reset()`，清空 COTE/BT/谓词/计时器。

### 3.8 预期效应与证伪

外部证据 [S16] 的时序集成增益是 1.9–2.3×（LIBERO），但那是 SmolVLA、LIBERO、不同动作空间。UniBot 上不能直接外推。本轮的保守目标是：

- **ACD/TW-ACD 降低 ≥10%**（TRB T0/T1）；
- **jerk 降低 ≥15%**（同）；
- **p99 < L/30**（L=4 时 <133ms；L=8 时 <267ms）；
- **真机 3 任务×10 次配对 +3pp 以上**（T3，仅作方向性判断）。

如果 ACD 不降、或者 p99 不达标、或者真机无增益，就回退到 COTE-Free 或纯 SURE-BT。**COTE 是主线，但不是信仰。**

## 4. TRB：低成本分层回放基准

### 4.1 四层阶梯

| 层 | 数据 | 方法 | 成本 | 产出 |
|---|---|---|---|---|
| T0 | 5% 留出 episode（~1,664 条） | 回放观测，比较预测动作与记录动作 | 1 卡小时级 | ACD、TW-ACD、jerk、谓词 F1 |
| T1 | T0 + label-preserving 扰动 | 背景替换、干扰物 copy-paste、颜色/材质变换、遮挡/丢相机 | 1 卡天级 | 轴间 gap、surprise AUROC |
| T2 | 3 个刚体任务 | MuJoCo/Isaac 闭环，校准刚体资产 | 1 卡 1–2 周 | 闭环成功率、恢复率 |
| T3 | 官方调试槽 | 3 任务×10 次，COTE on/off 配对 | 配额 | 真机方向性证据 |

T2 只做刚体、可校准的任务（StackBowls、StoreCups、HangCup 一类）；不做布料/拉链/透明全物理。这是第 8 轮“砍全孪生”的延续：**只造能校准的孪生，不造信仰。**

### 4.2 指标

| 指标 | 定义 | 用途 |
|---|---|---|
| ACD | 预测动作块与记录动作块的归一化 L2 | 执行层保真度 |
| TW-ACD | 最后 20% episode / 最后评分步骤加权 | 终端稳定性 |
| Jerk | 相邻 chunk 的动作差分 | 平滑度 |
| Surprise AUROC | 扰动 vs 正常相位切换的 `d` 区分度 | 免费检测器质量 |
| Predicate F1 | 谓词 vs 启发式/人工标签 | BT 可靠性 |
| Axis gap | 扰动 ACD − 干净 ACD | 泛化轴鲁棒性 |
| p50/p99 | `get_action` 延迟（N 端口并发） | chunk 合同 |

### 4.3 构造与成本

- 留出集：每任务随机 5% episode（约 50 条/任务），**按 episode 而不是按帧**，避免相邻帧泄漏；
- 锚点：每条 episode 取 10 个时间点（早/中/晚 + 抓取/放置附近），共 ~16,640 个；
- 推理：10Hz 时约 28 分钟；2Hz 时约 2.3 小时；
- T1：5 轴×2 条件 = 10×，约 5–23 小时；
- 不需要下载全量 0.8TB；用 HF 流式/按需下载留出集即可（全量体积见第三方摘要 [S25]）。

### 4.4 统计与校准

- 配对 bootstrap（按任务分层）；报告 95% CI；
- T0/T1 的 ACD 差异可以做到很小，但**ACD 与成功率的相关性未知**；必须用 T3 的 3 任务×10 次做校准；
- 如果 ACD 降了但 T3 不涨，说明指标不对，回退；
- 如果 T3 样本太小（30 次，SE 巨大），只看失败模式与方向，不做显著性宣称。

### 4.5 它不能证明什么

- 不能证明真机成功率；
- 不能替代官方 320 次；
- 不能测接触-rich 的力/柔顺；
- 不能测人扰的真实动态；
- 不能拿 T0/T1 的数字去排行榜上吹。

**TRB 是筛子，不是奖杯。**

## 2. 评分算术与统计功效

### 2.1 字典序目标

```text
maximize  S = (1/32) Σ_t (1/10) Σ_{r=1..10} 1[all steps completed in (t,r)]
subject to 每 episode ≤180s
tie-break: 步骤分（仅 S 相同）；再 tie-break: 提交日期
```

步骤分：

```text
P = (1/32) Σ_t (1/10) Σ_r Σ_i w_{t,i} 1[step i completed in (t,r)]
```

排序只用 S；P 是第二关键字。**任何提高 P 但降低 S 的策略都不划算。**

### 2.2 权重与噪声

| 量 | 值 |
|---|---:|
| 总 episode | 320 |
| 单任务权重 | 3.125pp |
| 单轴权重 | 20% |
| 单轴 episode | 64 |
| 单任务分辨率 | 10pp |
| SE(320, p=.3) | 2.56pp |
| SE(64, p=.3) | 5.73pp |
| SE(10, p=.3) | 14.5pp |
| 配对差值 SE(d=.15) | 2.17pp |
| 配对差值 SE(d=.20) | 2.50pp |

**决策规则**：+3pp 只当“可能有信号”；+5pp 才下结论；单任务 +10pp 不当真；轴级 <11pp 不当真。用配对种子/分层 bootstrap。

### 2.3 任务组合

- 每任务满值 3.125pp；“差一步”的任务翻到 50–80% 很便宜；
- 用 `flip_{t,k} ≈ S_{t,k-1} × (1 − S_{t,k}) × 3.125pp` 估上界；
- 但占位数据只有任务级 success/step，没有 step-level；真实 flip 需要调试槽或官方 step 日志。

### 2.4 终局与整条轨迹

第 8 轮把终局放置当“成功闸门”；本轮修正为：

- 终局仍是闸门（最后一步权重 20–50 分）；
- 但占位数据 gap 仅 6–10pp，不能支持“终局占大头”的强假设；
- 真正要修的是**整条轨迹的执行稳定性**：开环 chunk 的复合误差、接触误差、人扰后的恢复。

### 2.5 低成本后训练的期望收益上界

- 如果把 32 个任务的 gap 全修好，按占位数据上限约 +8–10pp；但这是合成数据，不可当真。
- 如果 COTE 只带来 +3pp，320 次真机约 1.4 SE，不够显著；所以必须先用 TRB 大样本筛选，再用 320 次确认。
- 如果负结果显示同分布 LoRA 无益，则把训练预算压到“谓词头/IB-Adapter/LPAA”这种有明确目标的模块。

## 3. COTE 规范

### 3.1 记号

| 符号 | 含义 |
|---|---|
| `t` | 全局控制步（30Hz） |
| `j` | 第 j 次 `get_action` 调用 |
| `Δ` | 自上次调用以来执行的步数（= `action_chunk_size`） |
| `H` | 模型原生 horizon（WLA=30） |
| `L` | 接口 `action_chunk_size`（返回步数） |
| `A_j[k]` | 第 j 次预测、第 k 步的绝对目标（EE 位姿或关节） |
| `B` | 上一次预测缓冲 |
| `d` | 归一化集成残差（surprise） |
| `s` | 当前评分步骤 id（来自 SURE-BT） |

### 3.2 算法伪代码

```python
class COTEPolicy:
    def __init__(self, base, L=8, H=30, lam=0.15, tau_d=3.0):
        self.base = base          # WLA-1.0-Base, same checkpoint
        self.L, self.H = L, H
        self.lam, self.tau_d = lam, tau_d
        self.reset()

    def reset(self):
        self.buf = None           # (A_prev, t_prev, step_id)
        self.step_id = 0
        self.last_obs = None

    def get_action(self, obs):
        # 1) same checkpoint, native H-step prediction
        rel = self.base.predict(obs, horizon=self.H)      # 54-dim relative
        abs_pose = integrate_relative(rel, obs)           # (H, D) absolute
        t = obs["t"]

        # 2) phase gate: only fuse within same score step
        if self.buf is None or self.step_id != self._predicate_step(obs):
            self.buf = (abs_pose, t, self.step_id)
            return self._pack(abs_pose[:self.L])

        A_prev, t_prev, _ = self.buf
        delta = t - t_prev

        # 3) divergence / surprise
        d = normalized_median_diff(abs_pose[0], A_prev[delta])
        if d > self.tau_d:
            self.buf = (abs_pose, t, self.step_id)
            self.surprise = d
            return self._pack(abs_pose[:self.L])          # trust new

        # 4) exponential fusion on overlap
        fused = fuse(abs_pose, A_prev, delta, self.lam)
        self.buf = (fused, t, self.step_id)
        self.surprise = d
        return self._pack(fused[:self.L])

    def _pack(self, chunk):
        # last step: soft endpoint (rate/accel limit; hold only if irreversible)
        chunk = soft_endpoint(chunk, self.step_id)
        return {"action...": chunk, "meta.token": TOKEN}
```

### 3.3 融合公式

```text
age = k + Δ
w_new = exp(-λ * age)
w_old = exp(-λ * k)
A_fused[k] = (w_new * A_j[k] + w_old * A_{j-1}[k + Δ]) / (w_new + w_old)
```

- λ=0.10–0.20；Δ=4 时新权重 ~0.55–0.60；Δ=8 时 ~0.30–0.45。
- 平移线性平均；旋转四元数 slerp；关节线性平均并夹限位；夹爪取最新 + 迟滞；腿/躯干默认最新。
- 若 `k+Δ >= H`（旧预测不够长），只用新预测。

### 3.4 参数表

| 参数 | 默认 | 范围 | 作用 |
|---|---:|---:|---|
| `L` | 8 | 4/8/16 | 反应性 vs 推理频率 |
| `H` | 30 | 30 | 模型原生 horizon |
| `λ` | 0.15 | 0.10–0.20 | 新预测权重衰减 |
| `τ_d` | 3.0 | 2–4 | 发散门控阈值（干净 95 分位的倍数） |
| `τ_s` | 2.5 | 2–4 | surprise 触发阈值 |
| `N_hyst` | 2 | 1–3 | 连续 N 个 chunk 才触发恢复 |
| `L_careful` | 4 | 4/8 | 不可逆步骤的 chunk |

### 3.5 surprise 信号

```text
d = median_d( |A_j[0,d] - A_prev[Δ,d]| / scale_d )
```

用途：

| 条件 | 解释 | BT 动作 |
|---|---|---|
| `d < τ_s` 且谓词稳定 | 正常 | continue |
| `d > τ_s` 且谓词未完成 | 人扰/滑脱/抓空/碰撞 | verify → recover |
| `d > τ_s` 且谓词刚完成 | 正常相位切换 | advance，清缓冲 |
| `d > τ_s` 连续 N 次 | 持续异常 | WaitClear / Regrasp / Reanchor |
| `d > τ_d` | 大变化 | 只用新预测，清缓冲 |

失败模式：快速运动、遮挡、相机抖动、接触瞬态都会抬高 `d`；必须用谓词、迟滞、几何校验（EE 位移、夹爪开合、腕部相机）联合判断。

### 3.6 与 SURE-BT 的接口

```text
每个 chunk 边界：
  obs → 谓词头 p(step done) → 信念 b_t
  COTE → d（surprise）
  BT Selector:
    if b_t.done and stable: advance / verify
    elif d > τ_s and not b_t.done: recover
    else: continue
  角色仲裁（support/act）→ 护理级别 → COTE 返回 chunk
```

BT 的 tick 周期 = `L/30` 秒；L=4 时 7.5Hz，L=8 时 3.75Hz。COTE 让 L=4 可行，从而把 BT 的反应性翻倍。

### 3.7 动作空间适配

WLA 的 EE 动作是相对 SE(3)（[S15]），提交 API 是绝对位姿（[S7]）。服务端必须：

```text
T_abs[0] = T_current * exp(Δξ_0)
T_abs[k] = T_abs[k-1] * exp(Δξ_k)
```

验收：

- 用 100 条官方 episode 回放，积分动作 vs 记录 EE 轨迹：平移误差 <1cm、旋转 <2°；
- 检查左右手、base/torso 坐标系；
- 检查夹爪方向（开/合）与数据一致；
- 检查 `control_space` 与返回键一致。

### 3.8 失败模式与回退

| 失败 | 现象 | 回退 |
|---|---|---|
| 跨相位平均 | 抓取/抬升之间犹豫 | 相位门控；谓词推进清缓冲 |
| 旋转平均错误 | 姿态绕远路/翻转 | 四元数 slerp；检查绕回 |
| 延迟超标 | 块间停顿 | L=8/COTE-Free；量化；多卡 |
| surprise 误报 | 频繁恢复 | 提高 τ_s；加迟滞；几何校验 |
| 旧预测过期 | 人扰后仍被拉回 | 发散门控；τ_d 调低 |
| 动作积分漂移 | 越走越偏 | 先修适配；不要上线 |

|---|---|---|---|
| `Relocalize(obj)` | 目标位移/丢失 | 重新检测→更新 6D 位姿→重算接近 | F1/F3 |
| `Regrasp(obj)` | 抓空/滑落 | 开爪→回撤→重对准→闭爪→抬升验证 | F5/F6 |
| `Reanchor(container)` | 容器/夹具位移 | 更新容器系→重算放置位姿/锚点 | F3 |
| `Redo(step)` | 谓词回退 | 从当前状态重做该步 | F2 |
| `Rewind(step)` | 多步回退 | 回退到受影响步骤，重做后续 | F2 |
| `WaitClear()` | 人手/遮挡 | 暂停/回撤→等清空→重观测 | F4 |
| `Nudge/Insert()` | 插入/闭合失败 | 柔顺小步搜索/微推/轻压 | F6 |
| `Abort()` | 不可逆/超时 | 停止恢复，保步骤分 | F9 |

### 4.4 双手角色图

- `Support(obj)`：稳定夹具/容器，保持位姿；
- `Act(obj, target)`：抓取/放置/插入/倾倒；
- `Handover`：角色交换；
- `Release`：释放。

从演示统计：低位移 + 持续接触/闭合 = Support；大位移 + 开合 = Act。BT 用 `Parallel(SupportHold, Act)`；支撑手漂移 >ε 时暂停 Act，`Regrasp(Support)`。

### 4.5 护理级别

| 级别 | 用于 | 参数 |
|---|---|---|
| fast | 自由空间运输 | 大 chunk、正常速度 |
| normal | 一般抓放 | 默认 |
| careful | 插入/倾倒/闭合/堆叠终局 | 小 chunk、限速、更多验证 |

护理边际价值近似 `V_i ∝ a_i × q_i × (1−r_i) × Δp_i / Δcost_i`；终局/不可逆步骤 `r_i≈0`，优先分配。

### 4.6 单模型合规

| 组件 | 类型 | 合规说明 |
|---|---|---|
| WLA-1.0-Base | 唯一 checkpoint | 主体 |
| 谓词头 | 同 checkpoint 辅助头 | 共享 backbone |
| COTE | 确定性代码 | 无学习参数 |
| SURE-BT | 确定性代码 | 可审计 |
| 恢复算子 | 代码+策略条件 | 不新增模型 |
| IB-Adapter | 同 checkpoint 模块（试验） | 需披露；默认 OFF |
| 外部检测器 | 不使用 | 默认 OFF |

## 5. TRB 四层回放基准

### 5.1 四层

| 层 | 数据 | 方法 | 成本 | 产出 |
|---|---|---|---|---|
| T0 | 5% 留出 episode（~1,664 条） | 回放观测，比较预测 vs 记录动作 | 1 卡小时级 | ACD/TW-ACD/jerk/F1 |
| T1 | T0 + label-preserving 扰动 | 背景/干扰物/颜色/遮挡/丢相机 | 1 卡天级 | 轴间 gap、AUROC |
| T2 | 3 个刚体任务 | MuJoCo/Isaac 闭环 | 1 卡 1–2 周 | 闭环成功率/恢复率 |
| T3 | 官方调试槽 | 3 任务×10 次，配对 | 配额 | 真机方向性证据 |

### 5.2 T0 构造

- 每任务随机 5% episode（按 episode 切，避免相邻帧泄漏）；
- 每条 episode 取 10 个锚点：早/中/晚 + 抓取/放置附近；
- 共 ~16,640 个锚点；
- 输入观测与官方 API 一致（4 相机、状态、language）；
- 输出动作与记录的未来 30 步比较；
- 归一化用数据集 `dataset_statistics.json` 的 scale。

### 5.3 T1 扰动

| 轴 | 构造 | 注意事项 |
|---|---|---|
| 背景 | 替换桌面区域颜色/纹理 | 保留物体/机械臂；用离线分割（SAM 等）需披露 |
| 干扰物 | 从其他 episode copy-paste 物体 | 不遮目标；保持阴影/尺度 |
| 未见物 | 目标物体颜色/材质变换 | 形状不变；动作标签保持 |
| 人扰遮挡 | 随机手形遮挡/丢一路相机 | 标签保持；测鲁棒性 |
| 位置 | 用数据自带的位置变化做 episode 级聚类留出 | 不做图像平移，避免动作标签错位 |

### 5.4 指标

| 指标 | 定义 | 用途 |
|---|---|---|
| ACD | 预测与记录动作块的归一化 L2 | 执行保真 |
| TW-ACD | 最后 20%/最后步骤加权 | 终端稳定性 |
| Jerk | 相邻 chunk 动作差分 | 平滑度 |
| Surprise AUROC | 扰动 vs 正常切换的 `d` | 检测器 |
| Predicate F1 | 谓词 vs 启发式/人工 | BT 可靠性 |
| Axis gap | 扰动 ACD − 干净 ACD | 鲁棒性 |
| p50/p99 | N 端口并发 `get_action` | chunk 合同 |

### 5.5 统计

- 配对 bootstrap（按任务分层），95% CI；
- T0/T1 样本大，ACD 差异容易显著；但**相关性未知**；
- T3 30 次样本，只能看方向/失败模式，不做显著性；
- 全量 320 次：+5pp 才下结论。

### 5.6 校准

- 用 T3 的 3 任务×10 次，计算 T0/T1 指标与真机成功率的 Spearman 相关；
- 若 |ρ|<0.5，弃用该指标，回到 T3；
- 若 ρ 高，用 T0/T1 做日常筛选，T3 做最终裁决。

### 5.7 局限

- 不能证明真机成功率；
- 不能测接触力/柔顺/布料；
- 不能测真实人扰动态；
- 不能替代官方 320 次。

## 8. 创新点清单（本轮迭代）

> 状态：押注=主线；保留=沿用；升级=旧点改造；试验=有希望但需证伪；降级=保留但非主回路；砍=不做。

### I1 SURE-BT：评分图编译的分块同步行为树（押注｜升级）
- **动机**：排名成功率先行；官方 32 任务评分图公开；主流 VLA chunk 内开环，长程/人扰易断。
- **差异**：不是 LLM 在线生成 BT，而是**离线编译官方评分图**；不是多模型 agent，而是**单 checkpoint + 确定性 BT**；不是随时 tick，而是**chunk 边界 tick + 软端点**。
- **可行性**：32 任务、2–5 步；BT 小；谓词可从演示训练；代码零推理成本。
- **资源**：1–2 人×2 周；CPU；无需额外数据。
- **步骤**：解析 info.json → 步骤图/偏序 → BT JSON → 谓词头 → 运行时接线 → 调试槽。
- **风险**：谓词噪声；BT 过约束；chunk 延迟。
- **状态**：主线。本轮用 COTE 残差替代风险头。

### I2 人扰剧本 → 恢复算子库（保留｜升级 NRB）
- **动机**：人扰 20% 权重且唯一动态轴；30/32 有官方备注；恢复是独立乘数。
- **差异**：从“自造扰动”升级为“官方备注分类 + 8 个恢复算子 + BT 触发”；T31/T32 自补剧本并标注假设。
- **可行性**：备注公开；64 条剧本；算子可参数化；同一 VLA 执行。
- **资源**：1 人×2 周；数据合成/回放。
- **步骤**：备注分类 → 算子实现 → 训练对 → BT 接线 → 调试槽。
- **风险**：备注≠测试；算子任务特定；过拟合。
- **状态**：主线支撑。

### I3 双手角色图 + 支撑手稳定器（保留）
- **动机**：约 14–16 任务双手；支撑手漂移是共性失败。
- **差异**：不改 VLA 架构；从演示挖角色标签；BT `Parallel(Support, Act)` + 稳定器；角色可交换。
- **可行性**：角色可从 EE/夹爪/接触统计；稳定器是控制器。
- **资源**：1 人×2 周；演示统计。
- **步骤**：角色挖掘 → 角色图 → BT 子树 → 稳定器 → T10/T19/T31 验证。
- **风险**：标签噪声；覆盖策略冲突；单模型合规。
- **状态**：高优先。

### I4 几乎成功前沿 + 任务组合（保留）
- **动机**：32 任务等权，单任务 3.125pp；“差一步”最便宜。
- **差异**：把步骤分当故障定位器；用 `drop/flip` 分配工程/调试槽；背包优化。
- **可行性**：BT 日志即可给步骤级成功率。
- **资源**：1 人×1 周；调试槽。
- **步骤**：日志 → S_{t,k}/drop/flip → 排序 → 分配。
- **风险**：小样本；过拟合调试条件；任务间迁移被低估。
- **状态**：保留（流程）。

### I5 护理级别分配（试验）
- **动机**：不可逆失败一次归零；均匀慢放浪费预算。

- **状态**：试验。

- **动机**：33k 成功演示里可能含 regrasp/retry；恢复数据稀缺。
- **差异**：用夹爪开合/EE 回撤/重复接近启发式挖恢复段；只做小规模 LoRA。
- **可行性**：状态/动作可算；标签噪声；需要人工抽检。
- **资源**：1 人×1–2 周；1 卡。
- **步骤**：启发式 → 抽检 → 数据集 → LoRA → TRB。
- **风险**：恢复段稀少；标签错；负结果 [S16]。
- **状态**：试验，优先级低于 COTE。

### I16 相对→绝对动作适配（新增｜工程）
- **动机**：WLA 输出相对 SE(3)，API 要绝对位姿；不做必偏。
- **差异**：显式积分、坐标系校验、回放 unit test；COTE 的前提。
- **可行性**：纯几何；几十行；可用官方数据验证。
- **资源**：1 工程师×2 天。
- **步骤**：积分 → 回放 → 误差 <1cm → 上线。
- **风险**：坐标系/旋转绕回/夹爪方向。
- **状态**：工程硬门槛。

### 已砍/降级
- 风险头 → 砍（COTE 残差替代）
- 大预算 LoRA/全参 → 移出主路径（负结果 [S16]）
- 每任务 LoRA/模型合并 → 砍（合规+维护）
- 全 32 任务高保真孪生 → 砍（成本/sim2real）
- 世界模型/WMA 主路径 → 砍（14B/延迟/成本）
- 外部数据/外部感知 → 默认 OFF（规则未明）
- 步骤分主目标 → 砍（字典序 tie-break）
