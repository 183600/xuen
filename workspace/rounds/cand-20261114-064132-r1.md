# 第 73 轮（承接第 72 轮「EMBODIED-GAUGE-RAS 具身计量审计」IP-287~294；灵感循环第 1 轮；本轮灵感：「失败恢复」×「意图理解」）

> R72 把 R71 的「认知层 GAUGE」下沉为具身系统：REG 实时执行图（调度即语义）、IRL 意图隐变量、DMEM 接触计量、EREFLEX 三层反作用、S2R-UQ 参数桥接，并用 **严格逐指令退化链**（定义 364）承诺「安全侧只增不减」。但 R72 的退化是**单向棘轮**：
> - **失败恢复视角**：R72 只回答「坏了怎么变安全」，没回答「好了怎么**回来**」。一次瞬态故障（意图 OOD 一瞬、触觉饱和、调度抖动、sim2real 残差瞬时超阈）就会把 `FULL` 永久钉死到 `R71`/`R68`。长时间部署下，这是**「安全但废掉」（fail-safe ≠ fail-operational）**：可用性单调塌缩，人类最终弃用。更危险的是**朴素恢复**——故障现象一消失就晋升——会把「看起来好了」当成「真的好了」，其危害可能**大于**一直降级。
> - **意图理解视角**：R72 把「虚晃」当 OOD 拒绝、把失败当纯降级触发。但**失败本身就是关于意图的证据**：抓取失败可能恰恰证明人原本是「指示/虚晃」而非「递交」；人也会**因为机器人失败而改主意**（重试／换目标／放弃／接管）。恢复必须**联合再认证测量链 + 重新理解意图**，而这两者会互相冒充：意图误读表现为任务失败，接触故障也表现为任务失败，**单点观测不可辨识**。
>
> 本轮两个灵感正好咬合：
> - **失败恢复**：把「降级」从单向棘轮升级为**双向认证模式格 BML**——降级即时、晋升须凭 **恢复证书 J_REC**（归因收敛 + 独立证据 + dwell 滞回 + 指标再验证 + 新鲜 epoch）；引入**恢复活性 RLV**：repairable 故障有限期望回归，persistent 故障有限期望升级到 human-handover，**不死锁在降级、不无限空转**。
> - **意图理解**：引入**恢复意图 z_rec**（retry/retarget/abstain/handover/query）与**意图修订**（失败作为反事实证据回灌 z）；把**故障归因 b_t(f)** 作为恢复策略的枢纽；用**恢复-归因 VoI（RA-VoI）** 选择「既恢复又去混淆」的主动诊断动作。
>
> 核心命题：**不再只问「坏了能不能变安全」，而问「我怎么**知道**它坏了、坏在哪一层、以及我怎么**带着证书**安全地回来——并且回来时，人和任务的意图还是不是我以为的那个？」** 把 R72 的具身计量审计升级为 **RECOVER-GAUGE-RAS**（Recovery-aware, Explanatory, Certified, Operational, Verified, Embodied, Reflexive GAUGE for RAS）——**可认证的失败归因与恢复闭环**。

## 0. 直觉与动机

**灵感 1（失败恢复 → 恢复不是降级的逆运算，而是「重新挣得信任」）**
直觉：在容错系统里，「检测到故障」与「确认已修复」是**两个不同的问题**，后者更难。R72 的 `IVG` 只做了前者。恢复的难点不在动作（松开、重抓、重规划都不难），而在**判据**：凭什么说「现在可以回 FULL 了」？R72 的证书 `J_EMB` 是**故障前**签发的，故障后它已经被污染；直接复用它等于**用旧地图找新大陆**。所以恢复必须签发**全新 epoch 的 J_REC**，且必须证明：故障根因已消除（cause_resolved）、指标确实回到有效域（metric_revalid）、且**不是同一条可能已坏的测量链在自证**（evidence_indep）。**「好了」必须被独立地、新鲜地、可反驳地证明。**

**灵感 2（失败归因 → 恢复质量的天花板是归因质量）**
直觉：同一个现象「抓取失败」，可能是 (a) 意图错（人其实想「推」）、(b) 接触错（滑移未检出）、(c) 时序错（快照过期用了旧位姿）、(d) 世界错（目标被拿走）。四种原因的恢复动作完全不同：重抓 vs 重标定 vs 等调度 vs 重新感知。**归因错 ⇒ 恢复动作错 ⇒ 要么振荡（恢复完又坏），要么把可修故障当不可修而过度升级。** 因此 R73 把归因 `b_t(f)` 放到恢复的入口，并把「归因是否可辨识」当作**晋升的硬前提**——归因不收敛，就**不许晋升**。

**灵感 3（意图理解 → 失败是意图的证据，失败后意图还会变）**
直觉：R72 把「虚晃」列入 `z` 但按 OOD 处置。实际上，**失败事件对意图后验有直接似然**：`p(e_t | z)`。若目标是「递交」，抓空不太可能；若目标是「虚晃／指示」，抓空完全合理。把失败当证据回灌，`b_t(z)` 会自发向「虚晃/指示」修订——这是从「被动接收指令」到「用结果反推意图」的关键一步。更现实的是，**失败会改变人的意图**：机器人抓空后，人可能说「算了，换那个」「还是我自己来」「再试一次」。这就是**恢复意图 z_rec**，它与原意图 `z` 联合决定恢复动作；若二者冲突（原意图=递交、恢复意图=接管），必须**先 query 再行动**。

**灵感 4（自我指涉 → 恢复证书必须跨通道、跨 epoch）**
直觉：恢复需要「测量链可信」的证明，但**可能坏的正是这条测量链**。若让触觉通道自己说「我修好了」，就是自证。R73 引入**独立证据原则**：每次晋升至少要有 **两条因果独立通道**（如触觉 vs 视觉+本体、调度硬件时间戳 vs 软件 WPET）同时支持「已恢复」，且证书绑定**单调 epoch** 与故障时刻，杜绝重放旧证书与伪造成。**恢复不是「问它好了没」，是「去问一个不共享故障源的证人」。**

**灵感 5（活性 → 但不能承诺「总能回 FULL」）**
直觉：对抗性持久故障（传感器物理损坏、目标被永久移走）**不可能**回 FULL。所以诚实的活性定义是：**有限时间收敛到一个稳定认证态**——要么回到 FULL，要么**升级到 human-handover**（一个合法、安全、可解释的稳定终态）。把「升级」当作成功而非失败，是 fail-operational 的核心：系统可以「安全地把方向盘交出去」，但不能「卡在中间反复试探」。

**灵感 6（反振荡 → 恢复本身会引入新故障模式：flapping）**
直觉：没有滞回和 dwell-time 的「降级-晋升」会形成 Zeno 振荡：降级→立刻晋升→再降级……每次振荡都在消耗人类信任与恢复预算，且**振荡本身可能被对抗者利用**（振荡 DoS）。所以 BML 必须带滞回带 `[θ_down, θ_up]` 与连续 k 周期验证；单位时间切换超阈即冻结晋升、进入保守观测期。

## 1. 形式化定义（增量：定义 366–379）

**定义 366（RECOVER-GAUGE-RAS 总览与六不变式）** RECOVER-GAUGE-RAS = (EMBODIED-GAUGE-RAS†, FAD, RIL, RCL, BML, RLV)。六不变式：
(i) **归因优先**：任何晋升决策前必须形成归因后验 `b_t(f)`；归因失效（不可辨识/未校准）⇒ **禁止晋升**，只能维持或继续降级；
(ii) **恢复证书独立证据**：晋升须凭 `J_REC`，且 `J_REC` 至少由**两条因果独立证据通道**支撑，断言通道不得自证；
(iii) **双向单调安全**：降级即时且永不失败；晋升时 `λ_floor` 不放松，恢复期风险界 ≤ R72 界；
(iv) **反振荡**：模式切换满足 dwell-time + hysteresis，禁止 Zeno；
(v) **恢复活性**：repairable 故障有限期望回归；persistent 故障有限期望升级到 human-handover；
(vi) **严格包含**：关闭 RCL/BML ⇒ 逐指令等于 R72（无安全回归，仅失去可用性增益）。

**定义 367（故障模式与故障事件）** 故障模式集
ℱ = ℱ_ψ ∪ ℱ_z ∪ ℱ_c ∪ ℱ_sched ∪ ℱ_world，
- `ℱ_ψ`：情感证据失效（AURA 失准、`ECE_aff` 超阈）；
- `ℱ_z`：意图失效（OOD、歧义、漂移、虚晃误判）；
- `ℱ_c`：接触失效（滑移未检出、标定漂移、力控暂态）；
- `ℱ_sched`：时序失效（deadline miss、熔断、WCET 超阈）；
- `ℱ_world`：世界/任务失效（物体滑落、目标被移走、人类干预）。
故障事件 `e_t = (symptom, context, timestamp, severity)`，其中 `symptom` 是跨域可观测向量（`rtm`、`breaker`、`slip`、`collision`、`intent_ood`、`human_cmd`）。

**定义 368（归因后验与归因校准）** 归因后验
`b_t(f) = p(f | e_{0:t}, ℋ_t)`。
归因器输出 `(b_t(f), ECE_attr, ι_attr)`，其中 `ECE_attr` 为归因校准误差，`ι_attr ∈ [0,1]` 为**归因可辨识度**（不同故障模式在观测分布上的可分性，由诊断图 `𝒢_diag` 的边权与混淆矩阵 `C_f` 计算）。**归因有效** ⇔ `max_f b_t(f) ≥ τ_attr ∧ ECE_attr ≤ τ_ece_attr ∧ ι_attr ≥ τ_iota_attr`。**归因有效是晋升的必要条件（定义 366-i）。**

**定义 369（恢复意图与意图修订）** 恢复意图
`z_rec ∈ {retry, retarget, abstain, handover, query}`。
失败作为意图证据（反事实回灌）：
`b_t^rev(z) ∝ p(e_t | z) · b_{t-1}(z)`，
其中 `p(e_t | z)` 是**失败似然**（如 `p(抓空 | 递交)` 低、`p(抓空 | 虚晃)` 高）。**联合恢复判据**：`b_t^joint = (b_t^rev(z), b_t(z_rec))`；若 `argmax b_t^rev(z)` 与 `b_t(z_rec)` 语义冲突（例：原意图=递交，恢复意图=接管）⇒ 强制 `query`，**不得自主晋升**。

**定义 370（恢复技能库）** `R_skills = {hold, reseat, regrasp, recalibrate, wait_settle, replan, query_human, handover, abort}`。每个技能 `r` 携带六元组 `(pre_r, eff_r, risk_r, evid_r, dur_r, tchain_r)`：前置条件、期望效果、风险界、可产出的独立证据、时长上界、追溯链。**技能可复合**，但复合后风险界取 `max` 而非 `sum`（安全侧保守）。

**定义 371（恢复证书 J_REC）** 
`J_REC = (epoch, cause_resolved, evidence_indep, metric_revalid, dwell_ok, budget_ok, attr_valid, ver)`。
`Valid(J_REC)` ⇔
`epoch > t_fault` ∧ `cause_resolved` ∧ `evidence_indep ≥ 2`（两条因果独立通道）∧ `metric_revalid`（指标回到有效域 `D`）∧ `dwell_ok` ∧ `budget_ok` ∧ `attr_valid`。
**关键**：`epoch` 必须严格大于故障时刻，**禁止复用故障前证书**（防回滚/重放/投毒）。`cause_resolved` 必须由**非归因通道**独立验证（定义 366-ii）。

**定义 372（双向认证模式格 BML）** 模式偏序 `R68 ≺ R71 ≺ EMBODIED`。降级边 `D`（即时、任意下移、无需证书）；晋升边 `P`（上移、须 `Valid(J_REC)`）。带滞回带 `[θ_down, θ_up]`（`θ_down < θ_up`）：指标跌破 `θ_down` 触发降级；回升超过 `θ_up` 且连续 `k` 个周期通过验证方可进入晋升候选。**晋升只发生在 `P` 边上，且永远可被下一次降级立刻打断（降级优先）。**

**定义 373（恢复活性/可用性）** 可用性 `A(T) = (1/T) ∫_0^T 1[mode(t)=FULL] dt`。恢复活性：
- repairable 故障过程下，`E[回归 FULL 的时间] ≤ T_rec`；
- persistent 故障过程下，`P(有限时间进入 human-handover) = 1`。
**注**：不承诺「总能回 FULL」（对抗性持久故障不可修复），只承诺「不死锁在降级、不无限空转、有限时间进入稳定认证态」。

**定义 374（反振荡 dwell 状态机）** 状态 `(c_up, c_down, last_switch_ts, window_history)`。晋升需 `dwell_up` 秒内无降级且计数达 `k`；降级即时。若窗口 `W` 内切换次数 `> N_flap`，**冻结晋升**并进入保守观测期 `T_cool`。由 dwell 保证：任意两次切换间隔 ≥ `dwell_min = min(dwell_up, T_obs)`。

**定义 375（恢复-归因 VoI，RA-VoI）** 恢复动作 `r` 的价值包含**恢复收益**与**归因信息增益**：
`VoI^RA(r) = ΔA(r) − c_rec(r) − c_reflex(r) + ξ·[H(b_t(f)) − E_{o_{t+1}} H(b_{t+1}(f))] + η·[H(b_t^rev(z)) − E H(b_{t+1}(z))]`。
**主动诊断**：选 `r` 既推进恢复、又区分「是意图错还是接触错/时序错」。**恢复动作可以「顺便」做实验。**

**定义 376（恢复预算与升级）** 恢复预算 `B_rec`，每次恢复消耗 `c_rec(r)`；与 R72 的 `B_reflex_total` 分离但耦合（恢复动作也产生反作用成本）。`B_rec` 耗尽 ⇒ **强制 human-handover**，而非继续重试。**「预算耗尽」是升级的合法触发，不是失败。**

**定义 377（威胁模型 AIC-REC）** `ℰ_REC = ℰ_EMB × ℰ_attr × ℰ_reenroll × ℰ_flap`：
- `ℰ_attr`：故障掩蔽（把接触故障伪装成意图故障，诱导错误恢复）、归因投毒；
- `ℰ_reenroll`：重入投毒（伪造 `J_REC`/复用旧 epoch）、乐观重入；
- `ℰ_flap`：振荡 DoS（触发降级-晋升循环耗尽预算与人类耐心）；
- `ℰ_rev`：意图修订注入（失败后伪造「改主意」，诱导错误 `z_rec`）。
防御：独立证据、epoch nonce、dwell 滞回、双通道一致性、人工确认。

**定义 378（严格包含与恢复安全）** 禁用 `RCL/BML` ⇒ 逐指令等于 R72（降级后不恢复，无回归）。启用后：**安全不变式 ≤ R72 界；可用性 ≥ R72**。**恢复是 R72 之上的一次可用性提升，不是安全回退。**

**定义 379（可解释恢复）** 每次恢复必须输出（对人）**归因摘要 + 拟采取动作 + 不确定性说明**；不确定时改为 `query`。人类可随时 veto。恢复透明度与 R71 的 `ψ`/信任耦合：失败降信任，**可解释的恢复可修复信任**（信任修复是恢复的隐性收益，进入 `ΔA` 的长期项）。

# IP-295 FAD：故障归因与诊断（计量域，软实时）
class FailureAttributor:
    def __init__(self, diag_graph, attr_model, calib):
        self.graph, self.model, self.calib = diag_graph, attr_model, calib
    def update(self, symptoms, b_f_prev, hpsi, hz, hc, sched):
        # symptoms: (rtm_flag, breaker, slip_prob, collision, intent_ood, human_cmd)
        b_f = self.model.posterior(symptoms, b_f_prev, hpsi, hz, hc, sched)
        ece = self.calib.expected_calibration_error(b_f)
        iota = identifiability(self.graph, b_f)          # 诊断图可分性
        valid = (b_f.max() >= TAU_ATTR and ece <= TAU_ECE_ATTR
                 and iota >= TAU_IOTA_ATTR)
        return Attribution(b_f=b_f, ece=ece, iota=iota, valid=valid)

# IP-296 RIL：恢复意图 + 失败作为意图证据
class RecoveryIntentLayer:
    def __init__(self, intent_hier, failure_likelihood, conflict_guard):
        self.hier, self.lik, self.guard = intent_hier, failure_likelihood, conflict_guard
    def revise(self, b_z_prev, failure_ev, human_obs, psi):
        b_z_rev = normalize(b_z_prev * self.lik(failure_ev, b_z_prev))  # 反事实回灌
        b_z_rec = self.hier.recovery_intent(human_obs, b_z_rev, psi)    # z_rec 后验
        conflict = self.guard.detect(b_z_rev, b_z_rec)
        return b_z_rev, b_z_rec, conflict          # conflict ⇒ 只能 query

# IP-297 RCL：恢复证书校验（晋升前唯一入口）
def valid_jrec(j, t_fault, channel_evidence):
    if j.epoch <= t_fault: return False                 # 禁复用故障前证书
    if not j.cause_resolved: return False               # 根因未消除
    # 至少两条因果独立通道，且任一通道不能是"待证通道"本身
    indep = independent_channels(channel_evidence)
    if len(indep) < 2: return False
    return (j.metric_revalid and j.dwell_ok and j.budget_ok and j.attr_valid)

# IP-298 BML：双向模式格（降级优先，晋升须证书 + 滞回 + dwell）
def mode_transition(cur, metrics, b_f, jrec, dwell, t):
    if metrics.below(THETA_DOWN) or not b_f.valid:       # 降级：即时、无条件
        return degrade(cur), reset_dwell(dwell)
    if cur is FULL: return cur, dwell
    # 晋升候选：需指标过 θ_up、归因有效、证书有效、dwell 满足
    if (metrics.above(THETA_UP) and b_f.valid and valid_jrec(jrec, t_fault, ev)
        and dwell.satisfied_up() and not dwell.frozen):
        return promote(cur), reset_dwell(dwell)
    return cur, dwell.tick()

# IP-299 RLV：恢复活性监控 + 升级（不承诺总能回 FULL）
class RecoveryLivenessMonitor:
    def __init__(self, T_rec, p_det, budget):
        self.T_rec, self.p_det, self.budget = T_rec, p_det, budget
        self.t_degraded_since = None
    def step(self, mode, t):
        if mode is not FULL and self.t_degraded_since is None:
            self.t_degraded_since = t
        if mode is FULL: self.t_degraded_since = None
        stuck = (self.t_degraded_since is not None
                 and t - self.t_degraded_since > self.T_rec)
        return stuck or self.budget.exhausted()   # ⇒ human-handover

# IP-300 RA-VoI：既恢复又去混淆的动作选择
def ra_voi(b_f, b_z_rev, z_rec, skills, budget, fmp):
    best = None
    for r in skills:
        if not r.pre(b_f, b_z_rev): continue
        if not budget.allow(r): continue
        dA   = expected_availability_gain(r, b_f)
        ig_f = entropy(b_f) - expected_post_entropy_f(b_f, r, fmp)   # 归因增益
        ig_z = entropy(b_z_rev) - expected_post_entropy_z(b_z_rev, r)
        score = dA - r.cost - r.reflex_cost + XI*ig_f + ETA*ig_z
        if best is None or score > best.score: best = (r, score)
    return best[0] if best and best[1] > 0 else None

# IP-302 RECOVER 主闭环（在 R72 三域分离之上加"恢复域"，仍在计量域执行）
def RECOVER_ROUND(M, obs, audio, tac_frame, human_cmd):
    # ---- 控制域（只读快照，与 R72 完全一致，恢复不阻塞控制）----
    k, lam, j_emb = EMBODIED_GAUGE_RAS_round(M, obs, audio, tac_frame)
    # ---- 计量域：归因 → 意图修订 → 恢复决策 ----
    if M.clock.due_metric():
        b_f = M.fad.update(M.symptoms(), M.b_f_prev, M.psi_hat,
                           M.hz, M.hc, M.sched)
        if not b_f.valid:
            M.bml.mode = M.bml.degrade(M.bml.mode)     # 归因失效 ⇒ 禁晋升
            M.registry.freeze('attribution_invalid')
        else:
            b_z_rev, b_z_rec, conflict = M.ril.revise(
                M.b_z_prev, M.last_failure, human_cmd, M.psi_hat)
            if conflict:
                r = 'query_human'
            else:
                r = M.ra_voi.choose(b_f, b_z_rev, b_z_rec, M.skills,
                                    M.budget_rec, M.fmp)
            if r is not None:
                out = M.skills.execute(r)               # 恢复动作（受 λ_floor 约束）
                M.budget_rec.spend(r.cost)
                M.jrec = M.rcl.build(epoch=M.epoch.next(), cause=out.cause,
                                     evidence=out.evidence, ...)
            # 晋升判据：证书 + 滞回 + dwell + 归因有效
            if M.rcl.valid(M.jrec, M.t_fault, M.channel_evidence):
                M.bml.try_promote(M.jrec)
        # 活性监控：卡在降级太久或预算耗尽 ⇒ 合法升级
        if M.rlv.step(M.bml.mode, M.clock.now()):
            M.bml.mode = 'HUMAN_HANDOVER'
        M.snapshot.write(M.bml.mode, b_f, b_z_rev, M.jrec)
    return k, lam, j_emb, M.bml.mode

# IP-303 恢复威胁防御：独立证据 + epoch + 双通道一致性
def guard_reentry(jrec, channels, epoch_now):
    if jrec.epoch != epoch_now: return False             # 防重放
    votes = [c.says_recovered() for c in independent_channels(channels)]
    agree = sum(votes) >= 2 and majority(votes)
    return agree and jrec.cause_resolved and not jrec.tainted

## 3. 推导

**引理 33（归因错误上界 ⇒ 恢复次优界）** 设归因误差 `ε_attr = P(f* ≠ argmax b_t(f))`，恢复代价函数对故障模式的敏感度为 `L_rec`（Lipschitz）。则按 `argmax b_t(f)` 选恢复动作 `r_attr` 的期望代价与最优 `r*` 之差 `≤ 2·L_rec·ε_attr`。证明：以 `ε_attr` 概率选错模式，错时最坏多付 `2L_rec`；线性期望即得。系：**归因是恢复质量的天花板——归因不准，恢复再好也只是「精确地修错地方」。**

**引理 34（独立证据 ⇒ 不可自证）** 若晋升要求至少两条**因果独立**通道且单通道潜伏故障概率 `≤ p`，则「故障通道自证已恢复」的概率 `≤ p²`（独立假设下）。证明：自证事件要求同一故障源同时污染两条独立通道，概率相乘。系：**恢复不能只问「你好了吗」——要问另一个不共享故障源的证人。** 这是 `J_REC.evidence_indep` 的正当性基础。

**引理 35（dwell + hysteresis ⇒ 无 Zeno）** 每次模式切换间隔 `≥ dwell_min`，则 `[0,T]` 内切换次数 `≤ T/dwell_min + 1`，有限；滞回带 `θ_down < θ_up` 使围绕阈值的抖动被吸收。故不存在 Zeno（有限时间无限切换），且振荡频率有上界。系：**反振荡不是调参，是可证明的时序性质。**

**引理 36（恢复活性）** 若故障每步可修复概率 `≥ p_rep > 0`、恢复动作期望时长 `≤ T_rec`、持久故障检出概率 `≥ p_det`，则：repairable 情形 `E[T_return] ≤ T_rec / p_rep`；persistent 情形 `E[T_escalate] ≤ 1 / p_det`。两种情形都有限 ⇒ **系统不会永远卡在降级。** 证明：几何分布期望 + 升级作为吸收态。

**引理 37（晋升安全单调）** 若每次晋升以 `Valid(J_REC)` 为前提，且 `J_REC` 含 `metric_revalid`（指标回到有效域 `D`）与 `λ_floor` 不放松，则晋升后风险界 `≤` 降级前 R72 界。证明：晋升只在 T2（R72 定理 24）条件全部重新满足时发生，故 R72 风险界重新成立；未满足则停留在更安全的下层。系：**恢复不是放松安全，是重新挣得安全。**

**定理 27（恢复的安全-活性权衡可同时达成）** 在归因可辨识（`ι_attr ≥ τ`）、独立证据可得、故障过程可修复或可检出下，存在恢复策略同时满足：(a) 任意时刻风险 `≤` R72 界；(b) 有限期望收敛到稳定认证态（FULL 或 human-handover）。证明：安全由引理 37 + R72 不变式保证（降级即时、晋升须再认证）；活性由引理 35、36 保证；二者不冲突，因为晋升是**可选**动作且只在再认证通过时发生，而降级是**无条件即时**动作——安全永远「先手」。**安全与活性可以同时要，代价是「回来必须有证据」。**

**定理 28（归因感知恢复严格优于朴素重入）** 朴素重入（故障现象消失即晋升、无归因、无独立证据）的期望代价 `≥` 归因感知恢复；且存在故障模式（掩蔽/持久）使朴素重入**无限循环或事故率上升**。证明：构造掩蔽故障——接触故障伪装成意图故障，朴素重入反复修错层，`ΔA = 0` 且 `c_rec` 累积；归因感知恢复因 `RA-VoI` 的 `ig_f` 项主动去混淆而收敛。系：**「看起来好了」不等于「好了」；恢复的判据比动作更重要。**

**定理 29（RECOVER 严格包含）** 关闭 `RCL/BML` ⇒ 逐指令等于 R72；开启 ⇒ 安全性不劣于 R72 且可用性 `≥` R72。证明：关闭时所有晋升禁用，退化为 R72 单向棘轮；开启时晋升是可选动作，不改变任何降级/控制路径，故安全界不降；且 `A(T)` 只会因晋升而增加。**恢复是 R72 安全超集上的可用性提升，不是安全回退。**

**定理 30（epoch 新鲜性 ⇒ 抗重放/投毒）** 若 `J_REC` 绑定单调 `epoch` 与故障时刻，且晋升检查 `epoch ≥ t_fault`，则任何重放旧证书或伪造的尝试被拒绝的概率 `≥ 1 − p²`（结合引理 34）。证明：旧证书 `epoch < t_fault` 直接拒绝；伪造需同时骗过两条独立通道。系：**新鲜性是恢复证书的安全语义，不是日志字段。**

## 6. 本轮最大风险

**一句话**：RECOVER-GAUGE-RAS 把安全从「相信计量审计证书」进一步升级为「相信**故障归因**与**恢复证书**」，但二者构成**自我指涉的信任闭环**——**用可能已经失准的测量链去判断「为什么失败」以及「是否已经恢复」；一旦系统性/掩蔽性故障被归因误判为偶发故障，系统会用一份「看起来合法、带新鲜 epoch、有两条通道投票」的 `J_REC` 反复「自信地晋升」回满能力，形成恢复—再故障振荡，每次振荡都在真机上消耗物理安全余量、恢复预算与人类信任，而事后审计只看到「每次晋升都有证书、每次降级都合规」，这就是**恢复层面的「自信地证明自己已经好了」**。**

次级风险与缓解：
1. **归因闭环/掩蔽** → **跨域独立证据 + 主动诊断**：归因必须由非归因通道交叉验证；`RA-VoI` 显式奖励去混淆动作；归因未达 `ι_attr` 阈值禁止晋升。
2. **乐观重入/证书自证** → **双独立通道 + 单调 epoch + 新鲜性检查**（引理 34、定理 30）；单通道永不单独定案。
3. **flapping/振荡 DoS** → **滞回带 + dwell-time + 冻结晋升 + 保守观测期**（定义 374、引理 35）；切换频次纳入审计。
4. **恢复预算被对抗性耗尽** → **内容签名去重 + 指数退避 + 预算耗尽即合法升级**（定义 376）。
5. **意图修订被注入** → **跨通道一致性 + 冲突强制 query + 人类 veto**（定义 369、379）。
6. **持久故障不可修却硬撑** → **活性定义只承诺稳定认证态**：persistent ⇒ 有限期望 human-handover，不承诺回 FULL（定义 373）。
7. **恢复拖慢控制环** → 恢复全部在计量域执行，控制域只读快照，`λ_floor` 不放松（定理 29 与 R72 定理 25）。

**最大风险一句话收束：真正的危险不是「恢复失败」，而是「系统用一条可能已经坏掉的尺子，反复证明自己已经修好了」。**

# 第 73 轮产物 · 创新点清单 v1：RECOVER-GAUGE-RAS（Recovery-aware, Explanatory, Certified, Operational, Verified, Embodied, Reflexive GAUGE for RAS；FAD×RIL×RCL×BML×RLV×RA-VoI）

> 承接第 72 轮 IP-287~294（EMBODIED-GAUGE-RAS）。R72 补上了具身层：REG 实时执行图、IRL 意图隐变量、DMEM 接触计量、EREFLEX 三层反作用、S2R-UQ 参数桥接，并用**严格逐指令退化链**（定义 364）承诺「安全侧只增不减」。但 R72 的退化是**单向安全棘轮**：
> - **缺失败恢复**：只回答「坏了怎么变安全」，没回答「好了怎么回来」。一次瞬态故障（意图 OOD、触觉饱和、调度抖动）永久钉死 `FULL→R71→R68`，长期部署可用性单调塌缩（fail-safe ≠ fail-operational）；朴素重入（现象消失即晋升）则可能比持续降级更危险。
> - **缺恢复证书**：恢复需要「测量链可信」的证明，但**可能坏的正是这条测量链**——自证是伪证。必须跨通道、跨 epoch 重新认证。
> - **缺失败归因**：同一现象（抓空）可能来自意图错/接触错/时序错/世界错，恢复动作完全不同；归因错 ⇒ 恢复错 ⇒ 振荡或过度升级。归因是恢复质量的天花板。
> - **缺意图理解（恢复语义）**：失败本身是关于意图的证据（抓空更可能是「虚晃/指示」而非「递交」）；失败后人的意图还会变（重试/换目标/放弃/接管），需要**恢复意图 z_rec**。
> - **缺活性**：R72 只保证安全（safety），不保证「不会永远卡在降级」（liveness）；也没有反振荡（flapping/Zeno）与恢复预算耗尽后的合法升级。
>
> 本轮两位一体补齐：
> - **失败恢复**：把「降级」升级为**双向认证模式格 BML**——降级即时、晋升须凭**恢复证书 J_REC**（归因收敛 + 独立证据 ≥2 通道 + dwell 滞回 + 指标再验证 + 新鲜 epoch）；**恢复活性 RLV** 承诺 repairable 有限回归、persistent 有限升级到 human-handover；**反振荡**用 dwell + hysteresis 证明无 Zeno。
> - **意图理解**：把失败作为**意图证据**反事实回灌 `b_t(z)`；引入**恢复意图 z_rec**；用**恢复-归因 VoI（RA-VoI）** 选「既恢复又去混淆」的主动诊断动作；冲突时强制 query，不自主晋升。
>
> 核心命题：**从「我的测量链在具身执行时还可信吗」进化为「我怎么**知道**它坏了、坏在哪一层、以及我怎么**带着新鲜、跨通道的证书**安全地回来——并且回来时，人和任务的意图还是不是我以为的那个？」** ——**可认证的失败归因与恢复闭环**。
>
> IP 编号：IP-295~304（共 10 个）+ R72 组件的 † 化。理论姿态延续：**新层是旧层的严格泛化，安全侧只增不减，退化链逐指令等价；恢复是可用性提升，不是安全回退。**

## 2. 形式化定义（要点版）

**定义 366（总览与六不变式）** 归因优先、恢复证书独立证据、双向单调安全、反振荡、恢复活性、严格包含。**归因失效禁止晋升；晋升必须跨通道再认证；降级永远先手。**

**定义 367（故障模式与事件）** 五类故障域 `ℱ_ψ/ℱ_z/ℱ_c/ℱ_sched/ℱ_world`；事件 `e_t` 跨域可观测症状向量。

**定义 368（归因后验与校准）** `b_t(f)=p(f|e_{0:t},ℋ_t)`；归因有效 ⇔ `max_f b_t(f)≥τ_attr ∧ ECE_attr≤τ_ece ∧ ι_attr≥τ_iota`。**归因有效是晋升必要条件。**

**定义 369（恢复意图与意图修订）** `b_t^rev(z)∝p(e_t|z)b_{t-1}(z)`；`z_rec∈{retry,retarget,abstain,handover,query}`；原意图与恢复意图冲突 ⇒ 强制 query。

**定义 370（恢复技能库）** 每技能六元组 `(pre,eff,risk,evid,dur,tchain)`；复合风险取 `max` 保守。

**定义 371（恢复证书 J_REC）** `Valid ⇔ epoch>t_fault ∧ cause_resolved ∧ evidence_indep≥2 ∧ metric_revalid ∧ dwell_ok ∧ budget_ok ∧ attr_valid`。**禁止复用故障前证书。**

**定义 372（双向认证模式格 BML）** `R68≺R71≺EMBODIED`；降级边即时无条件，晋升边须 `Valid(J_REC)` + 滞回 + 连续 k 周期。

**定义 373（恢复活性/可用性）** repairable：`E[T_return]≤T_rec`；persistent：`P(有限时间进入 human-handover)=1`。**不承诺总能回 FULL，只承诺有限时间进入稳定认证态。**

**定义 374（反振荡 dwell 状态机）** 晋升需 `dwell_up` 且计数达 `k`；窗口内切换超 `N_flap` ⇒ 冻结晋升 + 保守观测期。dwell 保证无 Zeno。

**定义 375（恢复-归因 VoI）** `VoI^RA(r)=ΔA−c_rec−c_reflex+ξ·IG_f+η·IG_z`；**恢复动作可「顺便」区分故障原因。**

**定义 376（恢复预算与升级）** `B_rec` 与 `B_reflex_total` 分离耦合；耗尽 ⇒ 强制 human-handover（合法终态）。

**定义 377（恢复威胁模型 AIC-REC）** 故障掩蔽、重入投毒/乐观重入、振荡 DoS、意图修订注入；防御：独立证据/epoch/dwell/双通道/人工确认。

**定义 378（严格包含与恢复安全）** 关闭 `RCL/BML` ⇒ 逐指令等于 R72；开启 ⇒ 安全 ≤ R72 界、可用性 ≥ R72。

**定义 379（可解释恢复 LEGIBLE-REC）** 归因摘要 + 拟采取动作 + 不确定性说明；不确定改 query；人类 veto；恢复透明度修复信任。

# IP-295 FAD：故障归因与诊断（计量域 50Hz）
class FailureAttributor:
    def __init__(self, diag_graph, attr_model, calib):
        self.graph, self.model, self.calib = diag_graph, attr_model, calib
    def update(self, symptoms, b_f_prev, hpsi, hz, hc, sched):
        b_f  = self.model.posterior(symptoms, b_f_prev, hpsi, hz, hc, sched)
        ece  = self.calib.expected_calibration_error(b_f)
        iota = identifiability(self.graph, b_f)
        valid = (b_f.max() >= TAU_ATTR and ece <= TAU_ECE_ATTR
                 and iota >= TAU_IOTA_ATTR)
        return Attribution(b_f=b_f, ece=ece, iota=iota, valid=valid)

# IP-296 RIL：失败作为意图证据 + 恢复意图
class RecoveryIntentLayer:
    def __init__(self, intent_hier, failure_likelihood, conflict_guard):
        self.hier, self.lik, self.guard = intent_hier, failure_likelihood, conflict_guard
    def revise(self, b_z_prev, failure_ev, human_obs, psi):
        b_z_rev = normalize(b_z_prev * self.lik(failure_ev, b_z_prev))
        b_z_rec = self.hier.recovery_intent(human_obs, b_z_rev, psi)
        conflict = self.guard.detect(b_z_rev, b_z_rec)   # 语义冲突
        return b_z_rev, b_z_rec, conflict                # conflict ⇒ 只能 query

# IP-297 RCL：恢复证书构建与校验（晋升前唯一入口）
def build_jrec(epoch, cause, evidence, metrics, dwell, budget, attr):
    return J_REC(epoch=epoch, cause_resolved=cause, evidence_indep=count_indep(evidence),
                 metric_revalid=metrics.in_valid_domain(), dwell_ok=dwell.ok,
                 budget_ok=budget.ok, attr_valid=attr.valid, ver=CERT_VER)

def valid_jrec(j, t_fault, channel_evidence):
    if j.epoch <= t_fault: return False                 # 禁复用故障前证书
    if not j.cause_resolved: return False               # 根因未由非归因通道验证
    indep = independent_channels(channel_evidence)
    if len(indep) < 2: return False                     # 至少两条因果独立通道
    return (j.metric_revalid and j.dwell_ok and j.budget_ok and j.attr_valid)

# IP-298 BML：双向模式格（降级优先，晋升须证书+滞回+dwell）
def mode_transition(cur, metrics, b_f, jrec, dwell, t_fault, ev):
    if metrics.below(THETA_DOWN) or not b_f.valid:
        return degrade(cur), dwell.reset()              # 降级：即时、无条件
    if cur is FULL:
        return cur, dwell
    if (metrics.above(THETA_UP) and b_f.valid
        and valid_jrec(jrec, t_fault, ev)
        and dwell.satisfied_up() and not dwell.frozen):
        return promote(cur), dwell.reset()
    return cur, dwell.tick()

# IP-299 RLV：恢复活性监控 + 升级（不承诺总能回 FULL）
class RecoveryLivenessMonitor:
    def __init__(self, T_rec, p_det, budget):
        self.T_rec, self.p_det, self.budget = T_rec, p_det, budget
        self.t_degraded_since = None
    def step(self, mode, t):
        if mode is not FULL and self.t_degraded_since is None:
            self.t_degraded_since = t
        if mode is FULL:
            self.t_degraded_since = None
        stuck = (self.t_degraded_since is not None
                 and t - self.t_degraded_since > self.T_rec)
        return stuck or self.budget.exhausted()         # ⇒ human-handover

# IP-300 RA-VoI：既恢复又去混淆
def ra_voi(b_f, b_z_rev, z_rec, skills, budget, fmp):
    best = None
    for r in skills:
        if not r.pre(b_f, b_z_rev): continue
        if not budget.allow(r): continue
        dA   = expected_availability_gain(r, b_f)
        ig_f = entropy(b_f) - expected_post_entropy_f(b_f, r, fmp)
        ig_z = entropy(b_z_rev) - expected_post_entropy_z(b_z_rev, r)
        score = dA - r.cost - r.reflex_cost + XI*ig_f + ETA*ig_z
        if best is None or score > best.score: best = (r, score)
    return best[0] if best and best[1] > 0 else None

# IP-302 RECOVER 主闭环（恢复域在计量域执行，不阻塞控制域）
def RECOVER_ROUND(M, obs, audio, tac_frame, human_cmd):
    # ---- 控制域（与 R72 完全一致；恢复不影响控制路径）----
    k, lam, j_emb = EMBODIED_GAUGE_RAS_round(M, obs, audio, tac_frame)
    # ---- 计量域：归因 → 意图修订 → 恢复 → 证书 → 模式迁移 → 活性 ----
    if M.clock.due_metric():
        b_f = M.fad.update(M.symptoms(), M.b_f_prev, M.psi_hat,
                           M.hz, M.hc, M.sched)
        if not b_f.valid:
            M.bml.mode = M.bml.degrade(M.bml.mode)      # 归因失效 ⇒ 禁晋升
            M.registry.freeze('attribution_invalid')
        else:
            b_z_rev, b_z_rec, conflict = M.ril.revise(
                M.b_z_prev, M.last_failure, human_cmd, M.psi_hat)
            r = 'query_human' if conflict else M.ra_voi.choose(
                b_f, b_z_rev, b_z_rec, M.skills, M.budget_rec, M.fmp)
            if r is not None:
                out = M.skills.execute(r)               # 受 λ_floor 约束
                M.budget_rec.spend(r.cost)
                M.jrec = M.rcl.build(epoch=M.epoch.next(), cause=out.cause,
                                     evidence=out.evidence,
                                     metrics=M.metrics, dwell=M.dwell,
                                     budget=M.budget_rec, attr=b_f)
            if M.rcl.valid(M.jrec, M.t_fault, M.channel_evidence):
                M.bml.try_promote(M.jrec)               # 证书+滞回+dwell 全过
        if M.rlv.step(M.bml.mode, M.clock.now()):       # 卡降级过久/预算耗尽
            M.bml.mode = 'HUMAN_HANDOVER'               # 合法稳定终态
        M.snapshot.write(M.bml.mode, b_f, b_z_rev, M.jrec)
    return k, lam, j_emb, M.bml.mode

# IP-303 恢复威胁防御：独立证据 + epoch + 双通道一致性
def guard_reentry(jrec, channels, epoch_now):
    if jrec.epoch != epoch_now: return False            # 防重放
    votes = [c.says_recovered() for c in independent_channels(channels)]
    agree = sum(votes) >= 2 and majority(votes)
    return agree and jrec.cause_resolved and not jrec.tainted

# IP-304 可解释恢复：归因摘要 + 拟动作 + 不确定性；冲突转 query
def legible_recovery(r, b_f, b_z_rev, z_rec, conflict):
    summary = explain_attribution(b_f)                  # 为何失败（top-k 归因）
    if conflict or b_f.iota < TAU_IOTA_ATTR:
        return Query(summary, reason='attribution_uncertain')
    return ExplainThenAct(summary, action=r, uncertainty=entropy(b_f))

## 4. 推导

**引理 33（归因错误上界 ⇒ 恢复次优界）** 归因误差 `ε_attr`、恢复代价对故障模式敏感度 `L_rec` ⇒ `cost(r_attr) − cost(r*) ≤ 2·L_rec·ε_attr`。系：**归因是恢复质量的天花板。**

**引理 34（独立证据 ⇒ 不可自证）** ≥2 条因果独立通道且单通道潜伏故障概率 `≤p` ⇒ 故障通道自证概率 `≤p²`。系：**恢复要问不共享故障源的证人。**

**引理 35（dwell+hysteresis ⇒ 无 Zeno）** 切换间隔 `≥dwell_min` ⇒ `[0,T]` 内切换 `≤T/dwell_min+1`，有限；滞回带吸收阈值抖动。系：**反振荡是可证明的时序性质，不是调参。**

**引理 36（恢复活性）** 故障每步可修复概率 `≥p_rep`、恢复时长 `≤T_rec`、持久故障检出 `≥p_det` ⇒ repairable `E[T_return]≤T_rec/p_rep`；persistent `E[T_escalate]≤1/p_det`。两者有限 ⇒ **不会永远卡在降级。**

**引理 37（晋升安全单调）** 晋升以 `Valid(J_REC)`（含 `metric_revalid` 与不放松 `λ_floor`）为前提 ⇒ 晋升后风险界 `≤` 降级前 R72 界。系：**恢复不是放松安全，是重新挣得安全。**

**定理 27（安全-活性可同时达成）** 归因可辨识 + 独立证据可得 + 故障可修复/可检出 ⇒ 存在策略同时满足 (a) 风险 `≤` R72 界；(b) 有限期望收敛到稳定认证态（FULL 或 human-handover）。证明：安全由引理 37 + R72 不变式；活性由引理 35、36；晋升是可选动作、降级无条件即时——安全永远先手，故不冲突。

**定理 28（归因感知恢复严格优于朴素重入）** 朴素重入期望代价 `≥` 归因感知恢复；掩蔽/持久故障下朴素重入可无限循环或事故率上升。系：**「看起来好了」≠「好了」；判据比动作更重要。**

**定理 29（RECOVER 严格包含）** 关闭 `RCL/BML` ⇒ 逐指令等于 R72；开启 ⇒ 安全不劣于 R72 且可用性 `≥` R72。**恢复是安全超集上的可用性提升，不是安全回退。**

**定理 30（epoch 新鲜性 ⇒ 抗重放/投毒）** `J_REC` 绑定单调 epoch 与故障时刻，晋升检查 `epoch≥t_fault` ⇒ 重放/伪造成功概率 `≤p²`（结合引理 34）。系：**新鲜性是恢复证书的安全语义，不是日志字段。**

| E390 基线对比 R72 | 是否显著优于 EMBODIED | Wilcoxon p<0.01, d≥0.5；归因树覆盖归因/意图/证书/活性四层 |

| E395 计量审计覆盖率 | 所有恢复决策是否有追溯链 | `TCHAIN` 覆盖率 100%，断链即禁晋升 |

## 7. 本轮最大风险

**一句话**：RECOVER-GAUGE-RAS 把安全从「相信计量审计证书」进一步升级为「相信**故障归因**与**恢复证书**」，但二者构成**自我指涉的信任闭环**——**用可能已经失准的测量链去判断「为什么失败」以及「是否已经恢复」；一旦系统性/掩蔽性故障被归因误判为偶发故障，系统会用一份「看起来合法、带新鲜 epoch、有两条通道投票」的 `J_REC` 反复「自信地晋升」回满能力，形成恢复—再故障振荡，每次振荡都在真机上消耗物理安全余量、恢复预算与人类信任，而事后审计只看到「每次晋升都有证书、每次降级都合规」，这就是恢复层面的「自信地证明自己已经好了」。**

次级风险与缓解：
1. **归因闭环/掩蔽** → 跨域独立证据 + 主动诊断（`RA-VoI` 奖励去混淆）；归因未达 `ι_attr` 阈值禁止晋升。
2. **乐观重入/证书自证** → 双独立通道 + 单调 epoch + 新鲜性检查（引理 34、定理 30）；单通道永不单独定案。
3. **flapping/振荡 DoS** → 滞回带 + dwell-time + 冻结晋升 + 保守观测期；切换频次纳入审计（引理 35）。
4. **恢复预算被对抗性耗尽** → 内容签名去重 + 指数退避 + 预算耗尽即合法升级。
5. **意图修订被注入** → 跨通道一致性 + 冲突强制 query + 人类 veto。
6. **持久故障不可修却硬撑** → 活性只承诺稳定认证态：persistent ⇒ 有限期望 human-handover。
7. **恢复拖慢控制环** → 恢复全部在计量域执行，控制域只读快照，`λ_floor` 不放松（R72 定理 25 保持）。

**最大风险一句话收束：真正的危险不是「恢复失败」，而是「系统用一条可能已经坏掉的尺子，反复证明自己已经修好了」。**
