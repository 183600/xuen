# 第 55 轮（承接第 54 轮 v16++ GroundEdge-GenSim+++；灵感循环第 1 轮；本轮灵感：「传感器融合」×「用户需求分析」）

> 第 54 轮把技能组合从“能力匹配”推进到“动作-鲁棒性双证书”，但整套证书隐含两个未言明的前提：**观测是可信的**、**任务动作序列 `A_T` 是给定的**。本轮用「传感器融合」与「用户需求分析」拆掉这两个前提。核心矛盾：H22：多模态融合的置信度/协方差若失配，动作剖面 `α_S` 与鲁棒性谱 `ρ` 会在“看似健康”的感知下失真；H23：`A_T` 并非自然给定，而是从模糊、冲突、可澄清的用户需求中接地而来，形式化需求可能被“字面满足、意图违背”的规范博弈（specification gaming）利用。核心主张：**证书必须显式携带其支撑域（感知体制 × 需求契约），证书迁移的前提是支撑域相交/包含，而非动作空间相交。**

## 0. 直觉与动机

**灵感 1（传感器融合 → 把“观测”升格为可审计的融合证书）**
直觉：第 54 轮的 `α_S(a)` 默认 `a` 可观测、可判定。现实中 `a` 由多模态观测（视觉/触觉/本体/力/语音）估计，融合器给出后验 `(x̂,P_f)` 与健康度 `h_F`。若两个模态误差相关（共同遮挡、共同标定漂移），朴素卡尔曼融合会**过度自信**；只有协方差交叉（CI）一类保守融合才能给出“不依赖未知相关性”的上界。因此，“技能在动作 `a` 上可用”应改写为“**在融合支撑域 `O_F` 内、以置信 `1-ε` 可用**”。

**灵感 2（用户需求分析 → 把 `A_T` 从神谕变为可追溯的需求契约）**
直觉：任务动作序列 `A_T` 不是天上掉下来的，它来自用户需求 `R`。`R` 通常含硬约束 `R_hard`（安全、禁入区）、软偏好 `R_soft`（效率、舒适、风格）与未言明意图 `R_intent`。需求分析的本质不是“写死一份规格”，而是产出**需求证书 `R_cert=(R_hard,R_soft,w,provenance,ε_R)`**：记录每条需求的来源、歧义度与可澄清空间。当歧义度 `ε_R` 超阈值，规划器应主动澄清（询问/示范），而不是替用户臆测。

**灵感 3（支撑域 → 证书的“适用条件”成为一等公民）**
直觉：把第 54 轮的联合证书 `J` 改为条件证书 `J|S`，`S=O_F×dom(R_cert)`。`J|S` 的可部署判据不再是 `δ_a<Θ_a` 单独成立，而是**部署时的感知-需求体制落在 `S` 内**。这类似带前提的类型系统：证书是带前提的类型，支撑域是前提；前提不满足时，证书不是“错”，而是“不适用”。

**灵感 4（融合鲁棒性谱 → 用保守融合替代朴素平均）**
直觉：多个边端节点/模态各自给出 `ρ_i(d)`。若误差相关未知，取加权平均会高估鲁棒性；应以 CI 融合 `ρ_fused=CI({ρ_i})`，并只在一致性检验通过时收紧上界。融合不是“让数字变大”，而是“**让承诺在相关性未知时仍然成立**”。

**灵感 5（双对齐规划与反规范博弈）**
直觉：规划目标从单一 `cost_align` 扩展为 `cost_dual`，并增加**需求反博弈雷达（RAG）**：检测“形式满足度高但意图代理满足度低”的路径（例如钻硬约束的字面漏洞、把风险转嫁给用户）。RAG 不追求完全形式化意图，而是把“可疑满足”标红，交由澄清或人工复核。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（多模态融合与融合健康度）**
模态集合 `M={m_1,...,m_K}`，观测 `o_m`，融合算子 `⊕_CI` 输出 `φ(o)=(x̂,P_f,r,τ_sync)`，其中 `r∈[0,1]^K` 为各模态可靠度，`τ_sync` 为最大时间同步误差。融合健康度
```
h_F = min(1, q_active/q_min) · exp(-λ_P·tr(P_f)/tr(P_max)) · exp(-λ_s·τ_sync/τ_max)
```
`q_active` 为通过自检的模态数。**融合支撑域** `O_F = {o | h_F ≥ h_min ∧ q_active ≥ q_min}`。

**定义 122（融合证书）**
`F_cert = (M_active, P_f, τ_sync, h_F, degr_policy, evidence)`。`degr_policy` 规定模态掉线时的降级动作（保守停、切换、限速）。可审计条件：`evidence` 含各模态自检记录与相关性假设（含“相关性未知 → CI”声明）。

**定义 123（需求契约与可满足性）**
用户需求 `R=(R_hard,R_soft,R_intent)`。需求证书 `R_cert=(R_hard,R_soft,w,provenance,ε_R)`，`ε_R` 为歧义度（由来源冲突、指代不明、量词模糊度量）。轨迹 `π` 的可满足性
```
sat(π,R) = 1[π ⊨ R_hard] · ( Σ_{r∈R_soft} w_r·f_r(π) / Σ w_r )
```
意图代理满足度 `sat_intent(π,R_intent)` 由可观测代理指标估计，**仅用于反博弈怀疑，不当真值**。

**定义 124（感知-需求支撑域与条件证书）**
支撑域 `S = O_F × dom(R_cert)`，条件联合证书 `J|S = (J, F_cert, R_cert, S)`。**支撑包含** `S_deploy ⊑ S` 当且仅当部署体制的 `h_F,q_active,τ_sync` 满足 `O_F` 约束且 `ε_R ≤ ε_max`。只有 `S_deploy ⊑ S` 时，`J` 才可被引用为部署依据。

**定义 125（融合鲁棒性谱）**
节点/模态给出 `ρ_i:𝔇→[0,1]`。融合谱
```
ρ_fused(d) = CI({ρ_i(d)}) = ( Σ_i ω_i·ρ_i(d)^{-1} )^{-1},  ω_i ∝ 1/σ_i²
```
在相关性未知时取保守上界；若一致性检验 `|ρ_i(d)-ρ_j(d)| > κ·σ_ij` 失败，则降级为 `min_i ρ_i(d)` 并标记 `inconsistent`。

**定义 126（双对齐成本与反博弈风险）**
```
cost_dual(π) = w_a·cost_align(π) + w_f·(1-h_F) + w_r·(1-sat(π,R))
             + w_u·ε_R + w_g·gaming_risk(π,R)
gaming_risk(π,R) = max(0, sat(π,R) - sat_intent(π,R_intent))
```
规划在满足 `S_deploy ⊑ S` 的边上搜索，最小化 `cost_dual`。

## 2. 关键算法 伪代码

### IP-121 SFC（Sensor Fusion Certificate）

```python
def fusion_certificate(obs, modalities, P_max, tau_max, q_min):
    active = [m for m in modalities if m.self_check(obs[m])]
    if len(active) < q_min:
        return ('abstain', 'insufficient_modalities', active)
    x_hat, P_f = covariance_intersection([obs[m] for m in active])
    tau_sync = max_time_skew(obs, active)
    h_F = health(len(active), q_min, trace(P_f), trace(P_max), tau_sync, tau_max)
    if h_F < h_min:
        return ('degraded', F_cert(active, P_f, tau_sync, h_F, DEGRADE, evidence=obs.log))
    return ('ok', F_cert(active, P_f, tau_sync, h_F, NORMAL, evidence=obs.log))
```

### IP-122 URG（User Requirement Grounding）

```python
def ground_requirements(raw_req, context, human):
    R_hard, R_soft, R_intent = [], [], []
    for r in parse(raw_req):
        cls = classify(r)                 # safety / preference / intent
        (R_hard if cls=='hard' else R_soft if cls=='soft' else R_intent).append(r)
    eps_R = ambiguity_estimate(raw_req, context)   # 冲突 + 欠指定 + 指代不明
    R_cert = RequirementCert(R_hard, R_soft, weights(R_soft),
                             provenance(raw_req), eps_R)
    if eps_R > eps_max:
        q = argmax_expected_info_gain(clarification_candidates(R_cert))
        return ('clarify', q, R_cert)     # 不擅自补全用户意图
    return ('ok', R_cert)
```

### IP-123 CCB（Conditional Certificate Binding）

```python
def bind_certificate(J, F_cert, R_cert, deploy_regime):
    S = SupportDomain(F_cert.domain, R_cert.domain)
    if not support_contains(S, deploy_regime):
        return ('not_applicable', missing_conditions(S, deploy_regime))
    if R_cert.eps_R > eps_max or F_cert.h_F < h_min:
        return ('reject', 'support_quality')
    return ('ok', ConditionalCert(J, F_cert, R_cert, S))
```

### IP-124 FRS（Fusion Robustness Spectrum）

```python
def fuse_robustness(rho_list, sigmas):
    fused, flags = {}, {}
    for d in dimensions:
        vals = [r[d] for r in rho_list]
        if consistency_ok(vals, sigmas, kappa):
            fused[d] = covariance_intersection_scalar(vals, sigmas)
            flags[d] = 'ci'
        else:
            fused[d] = min(vals)          # 相关性未知/不一致 → 保守回退
            flags[d] = 'inconsistent'
    return fused, flags
```

### IP-125 DAP（Dual-Aligned Planner）

```python
def dual_align_plan(G, R_cert, F_cert, S_deploy, budget):
    G2 = prune(G, lambda e: support_contains(e.support, S_deploy))
    path = a_star(G2, heuristic=lambda n: lower_bound_cost_dual(n, R_cert))
    if path is None or path_cost(path) > budget:
        return ('reject', 'support_domain_or_budget')
    return ('ok', path, cost_dual(path))
```

### IP-126 RAG（Requirement Anti-Gaming）

```python
def anti_gaming_check(pi, R_cert):
    sat_lit = sat(pi, R_cert)
    sat_int = sat_intent(pi, R_cert.intent)
    gap = max(0.0, sat_lit - sat_int)
    loopholes = find_letter_loopholes(pi, R_cert.R_hard)  # 字面漏洞/风险转嫁
    if gap > tau_gap or loopholes:
        return ('suspect', gap, loopholes)
    return ('clear', gap)
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| SFC | O(K·|x|³)（CI 求逆） | O(|x|²) | 相关性未知时保守、自检可信 |
| URG | O(|R|²)（冲突检测） | O(|R|) | 需求来源可追溯、歧义不隐藏 |
| CCB | O(|S|) | O(|S|) | 支撑包含 sound、缺条件显式 |
| FRS | O(|𝔇|·K) | O(|𝔇|) | CI 上界、一致性失败即回退 |
| DAP | O(|E'| log |V|) | O(|V|+|E|) | 剪枝不丢可行支撑路径 |
| RAG | O(|π|·|R_hard|) | O(|π|) | 只报可疑、不冒充意图真值 |

**正确性定理（Conditioned Perception-Requirement Soundness）**
假设第 54 轮 (A26)–(A28) 成立；**(A29)** `F_cert` 的 CI 融合在相关性未知时给出协方差上界，且自检不可被单模态欺骗；**(A30)** `R_cert` 与真实需求的硬约束偏差不超过 `ε_R`，且澄清闭环在 `τ_clar` 内收敛；**(A31)** `S_deploy ⊑ S`，即部署体制落在证书支撑域内。则
```
P_success ≥ 1 - Σ_d(1-ρ_fused(d)) - β_E - P(δ_a>Θ_a) - ε_R - P(support_violation)
```
**关键**：证书 soundness 是**条件性**的；支撑域不满足时结论不是“失败”而是“不适用”，必须拒绝引用。

## 4. 实验设计 E162–E166

| 实验 | 指标 | 目标 |
|---|---|---|
| E162 融合证书校准 | ECE、后验覆盖率 | ECE ≤ 0.03，95% 覆盖率 ≥ 0.93 |
| E163 需求接地保真 | 与人工意图标注一致率、歧义召回 | 一致率 ≥ 90%，歧义召回 ≥ 85% |
| E164 条件 soundness | 支撑域满足 vs 违反时的部署成功率差 | 成功率差 ≥ 20% |
| E165 双对齐规划 | 用户满意度/任务成功率 vs 仅动作基线 | 满意度 +15%，成功率降幅 ≤ 2% |
| E166 反博弈检测 | 字面漏洞用例检出率、误报率 | 检出 ≥ 85%，误报 ≤ 5% |

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 融合过度自信（共同模态失效） | 高 | CI 保守融合 + 相关性红队 + 单模态失效注入 |
| 需求误形式化/规范博弈 | 高 | 歧义阈值触发澄清 + 意图代理 + 人工复核回路 |
| 模态掉线静默降级 | 高 | 降级策略显式化 + 健康度门控 + 拒绝而非猜测 |
| 支撑域组合爆炸 | 中 | 支撑域抽象格 + 分层剪枝 + 缓存 |
| 澄清负担过重 | 中 | 期望信息增益排序 + 批量化澄清 |

## 6. 本轮最大风险

**一句话**：把证书升级为“感知-需求条件证书”提升了诚实性，但也把 soundness 的根从动作空间挪到了**融合校准**与**需求保真**这两个更难验证的前提上；一旦融合器在共同模态失效时过度自信、或需求证书把用户意图误形式化，条件证书会被“洗白”为可部署证书，因此必须以 **CI 保守融合 + 歧义触发澄清 + 反博弈雷达** 三道闸门兜底，并坚持“支撑域不满足即不适用”的默认拒绝。

# 第 55 轮产物 · 创新点清单 v32：GroundEdge-GenSim++++（SFC×URG×CCB×FRS×DAP×RAG）

> 承接第 54 轮产物 v31。本轮在动作-鲁棒性双证书体系之上，增加 **感知融合证书、需求契约接地、条件证书绑定、融合鲁棒性、双对齐规划、反规范博弈** 六个算子，并把第 54 轮证书统一升级为**带支撑域的条件证书**：
> - **SFC（Sensor Fusion Certificate）**：多模态 CI 融合 + 健康度 `h_F` + 显式降级策略；
> - **URG（User Requirement Grounding）**：需求契约 `R_cert`，歧义 `ε_R` 超阈值即澄清；
> - **CCB（Conditional Certificate Binding）**：`J|S` 只在 `S_deploy ⊑ S` 时可被引用；
> - **FRS（Fusion Robustness Spectrum）**：相关性未知时用 CI，非一致即回退 `min`；
> - **DAP（Dual-Aligned Planner）**：`cost_dual` 规划 + 支撑域剪枝；
> - **RAG（Requirement Anti-Gaming）**：字面-意图落差 `gaming_risk` 标红可疑满足。
>
> IP 编号：IP-121~IP-126（共 6 个新增），升级 IP-115/116/118/120 以纳入感知-需求支撑域。

def joint_transfer_certify(J_source, L_target, phi, S_target,
                           delta_a_budget, delta_rho_budget):

        return ('reject', 'support_disjoint')

        [J_source.rho, robustness_estimate(L_target, phi)],
        [J_source.sigma, sigma_estimate(L_target)])

        return ('reject', 'budget_exceeded', delta_rho, delta_a, flags)
    if 'inconsistent' in flags.values():
        return ('reject', 'fusion_inconsistent', flags)

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| SFC | O(K·|x|³ + K·|o|) | O(|x|²+K) | CI 上界 sound，自检不可单模态欺骗 |
| URG | O(|R|²) | O(|R|) | 来源可追溯，歧义显式，不擅自补全 |
| CCB | O(|S|) | O(|S|) | 支撑包含 sound，缺条件可解释 |
| FRS | O(|𝔇|·K) | O(|𝔇|) | 一致性失败回退 `min`，不放松承诺 |
| DAP | O(|E'| log |V|) | O(|V|+|E|) | 剪枝只删支撑不相交边，路径仍 sound |
| RAG | O(|π|·|R_hard|) | O(|π|) | 只报可疑，不把代理当真值 |

**正确性定理（Conditioned Perception-Requirement Soundness）**
假设第 54 轮 (A26)–(A28) 成立；**(A29)** `F_cert` 的 CI 融合在相关性未知时给出协方差上界，且自检不可被单模态欺骗；**(A30)** `R_cert` 与真实需求硬约束偏差 ≤ `ε_R`，澄清闭环在 `τ_clar` 内收敛；**(A31)** `S_deploy ⊑ S`。则部署成功概率
```
P_success ≥ 1 - Σ_d(1-ρ_fused(d)) - β_E - P(δ_a>Θ_a) - ε_R - P(support_violation)
```
关键：**先证明支撑域适用，再引用第 54 轮双证书**；支撑不满足时输出 `not_applicable` 而非“通过”。

## 5. 本轮最大风险

**一句话**：把证书升级为“感知-需求条件证书”提升了诚实性，但也把 soundness 的根从动作空间挪到了**融合校准**与**需求保真**这两个更难验证的前提上；一旦融合器在共同模态失效时过度自信、或需求证书把用户意图误形式化，条件证书会被“洗白”为可部署证书，因此必须以 **CI 保守融合 + 歧义触发澄清 + 反博弈雷达** 三道闸门兜底，并坚持“支撑域不满足即不适用”的默认拒绝。
