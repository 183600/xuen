## 1. 直觉与动机（两个灵感的碰撞）

### 灵感 1（任务规划 → VLA 会做动作，但不知道「做到第几步」）

**直觉**：32 个任务里大量是多阶段长程任务（OrganizeBookshelf、PackBag、ToolboxStorage、ArrangePlates、PaperCupStacking…），官方又按「得分点」逐步给分（F17/F24）。端到端 VLA 每一步只看当前帧和一句语言，天然缺少一个显式的「任务状态」：它可能提前收手、重复子步骤、或在某一步失败后继续执行后续 chunk。人类操作者做这些任务时脑子里有一张 checklist——这就是任务规划。反直觉点：**在步骤分制度下，显式知道「下一个得分点是什么」可能比把动作拟合得更像示教更值钱**，因为它直接决定步骤分，而步骤分是超时/部分完成时唯一还在累积的分数（F3）。

**严谨定义**：把每个任务建模为**子目标图上的分层 POMDP**：

- 子目标图 `G = (V, E, w)`，`V = {g_0, …, g_m}`，`g_0` 初始、`g_m` 成功；边 `(g_i, g_j) ∈ E` 表示可执行转移；`w: V → [0,100]` 是该子目标对应的官方得分点权重（可均分，或从 wiki/挑战页逆向）。
- 信念 `b_t = p(s_t | o_{1:t}, a_{1:t})`。
- 高层策略 `π_hi(g' | b_t, g_t)` 在 `G` 上选下一子目标；低层策略 `π_lo(a_{t:t+T_a} | b_t, g', ℓ)` 即 VLA，`ℓ` 为语言指令。
- 子目标完成检测器 `D(b_t, g) → {0,1}`；当 `D` 连续 `τ` 步为 0、或进度头下降、或接触状态异常（见灵感 2）时触发重规划。
- 目标：`max E[ Σ_{s∈V} w_s · 1(s 达成) ]`，`s.t.` 单步延迟 ≤ 预算。步骤分即该目标函数的一次实现。

这把「任务规划」从一句口号变成可训练、可消融、可与官方得分点对齐的目标函数。

### 灵感 2（传感器融合 → 没有力觉，但机器人有 4 只眼睛和本体感觉）

**直觉**：接口没有力/触觉/电流（F21），而 32 任务里接触密集的至少 8 个（PlugCharger、ZipUp、Unlock、PourOutMedicine、SyringeWaterTransfer、PlugInEthernet、DisconnectEthernet、PaperCupStacking…）。但接口给了 4 路 RGB（头双目+腕双目，F20）和完整本体感觉（F21）。接触在视觉上并非不可见：插头插进去时腕部光流会突然一致、夹爪开度会顶住、末端指令位姿与实际位姿会出现残差、物体在夹爪里会滑动。把这些弱信号融合起来，可以**推断**出一个「伪触觉」接触状态——不是测力，而是估计「现在处于 free / approach / contact / slip / stable_grasp / release 中的哪一种」。反直觉点：**缺失的模态不必用新硬件补，可以用多视角冗余 + 本体感觉的时序不一致性补**。

**严谨定义**：观测 `o_t = (I^h_L, I^h_R, I^w_L, I^w_R, q_t, x^{ee}_t, u_t, g_t)`，其中 `q` 为关节、`x^{ee}` 为 base 系末端位姿、`u` 为夹爪开度、`g` 为 lower_body。设隐状态 `s_t = (s^{obj}_t, s^{robot}_t, c_t)`，`c_t ∈ C = {free, approach, contact, slip, stable_grasp, release}` 为接触模式。伪触觉即后验 `p(c_t | o_{1:t}, a_{1:t})`，由融合编码器 `f_θ` 估计。

可辨识性假设：`c_t` 通过四类可观测量体现——(i) 腕部光流的一致性/散度（滑移），(ii) 夹爪开度动力学与指令的偏差（顶住/夹稳），(iii) 末端指令位姿与实际位姿残差 `r_t = ||x^{cmd}_t − x^{state}_t||`（接触阻力），(iv) 物体-夹爪相对位姿变化（头/腕双目三角化后的一致性）。在这些信号存在时，`c_t` 可在分类器容量内被辨识；不可辨识区间用置信度门控退回「无接触先验」，避免误触发。跨视角几何：头双目与腕双目各自三角化；腕部外参可由 `ee_pose` 推出（刚性安装），头部外参需 reset 期标定或由 `lower_body` 估计（F27，待核实）。

### 灵感 3（碰撞：任务规划 × 传感器融合 = 任务条件化的主动感知）

**直觉**：两个灵感不是并列的两块，而是一个闭环：规划器知道「下一步该抓杯子」，就能告诉融合模块「只看杯子所在的腕部区域」；融合模块估计出「已经夹稳/正在滑」，就能告诉规划器「这个子目标完成了/失败了，该重规划」。没有规划，融合不知道看哪里、算力均摊；没有融合，规划不知道子目标到底完成没有、只能盲信。更关键的是，这个闭环天然解决部署预算：**只在规划不确定性高的 chunk 边界做重融合，其余步只做轻量跟踪**。反直觉点：**传感器融合的正确预算不是「每步都全量融合」，而是「由任务规划的不确定性来分配」——感知为规划服务，规划为感知省算力。**

**严谨定义（PR6 任务条件化融合）**：在每个 chunk 边界，规划器输出子目标后验 `π_hi(· | b_t)`；融合调度器选择感知模式 `s ∈ {none, wrist, head, full-stereo}`：

```
s* = argmax_s  IG(s ; g') / cost(s),   s.t.  Σ cost(s) ≤ 单步预算
```

其中 `IG(s ; g')` 是模式 `s` 对下一子目标判定的期望信息增益（可用子目标后验熵的下降近似），`cost(s)` 是该模式的实测延迟。这等价于一个在线背包/信息增益分配问题。它把「传感器融合」从固定管线变成**任务条件化的计算分配策略**，同时服务计分（子目标判定更准）与预算（少算无用视角）。

**三者统一（本轮结论）**：v1.1 的胜负手在训练数据（把分布搬进考纲）；本轮指出推理期还缺两个状态——**任务状态**（I10）与**接触状态**（I11），而二者通过任务条件化融合（PR6）互相供给。数据侧解决「会不会」，规划/融合解决「做完没、做成没、下一步做啥」。

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2）

> 检索日期：2026-11-27（本轮）；来源见 §5。承接 v1.1：**I10/I11 新增，I3/I4/I5/I6/I8 深化，I7 修剪，I1/I2/I9 维持**。本轮主线：用「任务状态 + 接触状态」两个推理期状态，把步骤分与接触密集任务从「隐式」变成「显式」。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I10 得分点图分层子目标规划 ★★★★★（新）

- **动机**：P9/F17/F24。长程任务多、步骤分逐点累积；端到端 VLA 无显式任务状态，易跳步/重复/失败后不重规划。
- **与现有方案差异**：① 纯端到端 VLA：无任务状态，步骤分只能靠隐式进度头；② LLM-planner 外挂：引入第二个大模型，违反单模型边界与延迟预算；③ 本点用 **goal-token** 把子目标条件注入同一个 VLA，规划器只是同一模型特征上的轻量头（或 FSM 兜底），零额外基座。
- **技术可行性**：中-高。子目标图可半自动构建；goal-token 是条件化训练，不改变推理图结构。
- **所需资源**：1×24GB（复用官方 frozen-VLM/LoRA，F11）；子目标图构建 1 人周；goal-token 微调 1–2 GPU 日；检测器复用 I5。
- **落地步骤**：
  1. **得分点逆向**：抓取挑战页 JS 数据端点 + 任务 wiki，得到每任务有序得分点；拿不到时用示教变点分割兜底。
  2. **子目标图**：示教分段 → 跨示教 DTW 对齐 → 合并为 `G=(V,E,w)`；人工抽检 5%。
  3. **goal-token**：在 VLA 的条件输入（语言/视觉 token 序列）前拼接可学习的子目标嵌入；训练时用分段边界作子目标标签。
  4. **完成检测器**：`D(b_t,g)` 复用 I5 的轻量里程碑检测器；输出子目标完成概率与置信度。
  5. **重规划状态机**：完成→推进；连续 τ 步未完成/进度下降/接触异常→回退或换后继子目标。
  6. **消融**：goal-token on/off、规划粒度、重规划触发阈值。
- **风险**：
  - 子目标粒度过细 → 检测噪声主导；过粗 → 步骤分收益小。缓解：L0 扫粒度，以「步骤分代理增益 / 检测误差」定档。
  - goal-token 训练数据不足（每任务仅数百 eps）。缓解：跨任务共享子目标类型（抓/移/放/插/拧/倒），按技能而非按任务建 token。
  - 单模型边界：goal-token 属同一模型内条件化，风险低；FSM 兜底方案作为合规降级。
- **子目标分割的严谨定义**：给定融合状态序列 `x_1…x_n`（物体位姿+夹爪+末端），分段为
  `argmin_{0=t_0<…<t_k=n} Σ_i cost(x[t_{i-1}:t_i]) + λ·k`，
  其中 `cost` 为段内状态方差（物体相对运动 + 夹爪状态），`λ` 为复杂度惩罚；再用 DTW 把不同示教的分段对齐成规范子目标序列。λ 由 L0 的步骤分代理选。

### I11 多视角-本体感觉伪触觉融合 ★★★★★（新）

- **动机**：P10/P4/F20/F21。无力/触觉/电流，接触密集任务缺显式接触状态；滑移、空抓、过力只能在失败后从画面看出。
- **与现有方案差异**：① 买力传感器/触觉皮肤：赛题接口无该通道，且增加硬件与集成风险；② I3 几何伺服：是「接触段怎么动」的执行器，不提供统一的接触状态；③ 本点用 **4 路 RGB + 本体感觉 + 动作历史**推断 `p(c_t|o_{1:t})`，作为 I3/I4/I5 的共享触发/门控信号。
- **技术可行性**：中。特征可分性可先离线验证（不训模型）；sim 接触标签可用（F26）；误报用置信门控控制。
- **所需资源**：1×24GB；立体匹配只在关键帧（预算调度，见 PR6）；1 人周特征工程 + 1 GPU 日分类器。
- **落地步骤**：
  1. **特征提取**（全部来自 F20/F21，无需新硬件）：腕部光流一致性/散度、夹爪开度导数、末端指令-实际残差 `r_t`、头/腕双目三角化后的物体-夹爪相对运动、多视角遮挡/不一致。
  2. **标签**：sim（Isaac Lab 接触传感器，F26）给强标签；示教里程碑（抓取段=contact/stable、释放段=free）给弱标签；I5 的扰动合成给 slip 正例。
  3. **估计器**：轻量时序分类器（GRU/TCN）输出 6 类后验；温度缩放校准，报告 ECE。
  4. **门控与触发**：`p(contact)` 触发 I3 接触段接管；`p(slip)` 触发 I5 重抓；`p(free)` 抑制误触发。
  5. **验证**：离线 AUC/F1/ECE → 真机抽测接触密集 3 任务。
- **风险**：
  - sim2real 差距：视觉纹理/摩擦不同。缓解：只用 sim 学表征、用真机无标签数据做域适配；先验证「不训模型的特征阈值」下限。
  - 误报伤原本会做的任务：缓解：高置信才触发 + 回退到无接触先验；L0 验证标称场景 Δ 成功率 ≥0。
  - 头部外参未知（F27）：缓解：腕部为主、头部为辅；reset 期标定；假设 episode 内躯干固定。
- **特征-接触模式对应表**（离线先验，待数据验证）：

| 特征 | free/approach | contact | slip | stable_grasp |
|---|---|---|---|---|
| 腕部光流一致性 | 低/随动 | 突增 | 高且物体随夹爪 | 低 |
| 夹爪开度导数 | ≈指令 | 被顶住（<指令） | 抖动/回弹 | 稳定 |
| 末端残差 `r_t` | ≈0 | 上升 | 上升 | 平台 |
| 头/腕物体相对运动 | 大（接近） | 趋零 | 非零（滑动） | ≈0 |

### I3 v3 接触任务族关键点视觉伺服回退 ★★★★（深化）

### 1.1 子目标图构建（I10）

```python
def build_subgoal_graph(demos, lam):
    """demos: 每任务的示教序列；返回规范子目标图 G=(V,E,w)。"""
    seqs = []
    for x in demos:                                  # x: 融合状态序列（物体位姿+夹爪+末端）
        # 最优分段：段内方差 + λ·段数（动态规划）
        cuts = optimal_partition(x, cost=within_segment_var, penalty=lam)
        segs = [summarize(x[a:b]) for a, b in cuts]  # 每段一个「子目标原型」
        seqs.append(segs)
    proto = dtw_align(seqs)                           # 跨示教对齐成规范序列
    V = canonicalize(proto)                           # 合并近邻原型
    E = consecutive_edges(V) | optional_edges(V)      # 顺序边 + 可跳过边（如可并行）
    w = score_weights(V)                              # 官方得分点权重；缺失则均分
    return Graph(V, E, w)
```

### 1.2 分层规划与重规划（I10）

```python
class ScoreGraphPlanner:
    def reset(self, task_graph):
        self.G, self.g, self.stuck = task_graph, task_graph.g0, 0
    def update(self, b_t, contact):                   # b_t: 融合信念；contact: I11 后验
        done = self.D(b_t, self.g) > 0.5
        bad  = contact.p_slip > 0.7 and contact.p_stable < 0.3
        self.stuck = 0 if done else self.stuck + 1
        if done:
            self.g = self.advance(b_t, self.g); self.stuck = 0
        elif self.stuck > TAU or bad:
            self.g = self.replan(b_t, self.g)          # 回退/换后继
        return self.g
    def advance(self, b, g):
        return argmax(self.G.successors(g), key=lambda g2: self.Q_hi(b, g2))
    def replan(self, b, g):
        # 优先回到最近未完成子目标；接触异常时先回退到抓取子目标
        return self.nearest_unfinished(b) if not self.bad_contact else self.grasp_of(g)
```

### 1.5 任务条件化主动感知（PR6 / I11 调度器）

```python
def choose_sensing(belief, g_next, budget_ms):
    best, best_score = "none", 0.0
    for s in ["none", "wrist", "head", "full-stereo"]:
        if latency[s] > budget_ms:
            continue
        ig = expected_information_gain(s, g_next, belief)     # I(g'; o_s | b)
        score = ig / latency[s]
        if score > best_score:
            best, best_score = s, score
    return best
```

### 1.6 闭环 `get_action`（组合 I10/I11/I4/I5）

```python
def get_action(self, obs):
    if not self._init:
        self.reset(obs)                                   # reset 期标定 + 检索（I9）+ 初始化
        self._init = True
    contact = self.pseudo_tactile(obs, self.last_cmd)     # I11
    if self.at_chunk_boundary():
        mode = self.choose_sensing(self.belief, self.g, BUDGET_MS)  # PR6
        self.belief = self.fuse(obs, mode, self.belief)
        self.g = self.planner.update(self.belief, contact)          # I10
    chunk = self.vla.propose_chunk(obs, self.lang, self.g)         # goal-token
    chunk = self.guard_stack(chunk, obs, contact)                  # I3/I4/I5
    self.last_cmd = chunk
    return chunk
```

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|

- I10：若 L0 子目标分割跨示教一致率 <0.5，或 L2 步骤分增益 <2 分 → 降级为「仅进度头监督」，不做显式规划。
