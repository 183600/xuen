# 研究循环 · 新灵感三元组第 1 轮（v23 提案）；本轮灵感：「竞赛策略」×「边缘计算」

> **基线**：第 3 轮产出 MetricVoiceGauge-NCD-HUTDH-v22 + IP-431–435（HDL/ACSC/DCSC/HPC-E/CFC++；其下承 v21 的 SDC/CAC/DCL/GIC/HPC+、v20 的 PCA/CTS/CFC/HPC/CFCtrl、v19 证书体系、v17 感知链）。
> **本轮纪律**：不推倒 v22。能量/语义/规范/几何各层全部保留，`Exec_v23 ⊆ Exec_v22` 必须闭环。本轮只做一件事：**在 v22 的"安全可行"之上补上被长期忽略的"稀缺性"维度——当多机器人同时争夺共享空间、路权、充电位与边缘算力时，谁先走、用哪个边缘节点、证书在什么时效内仍然算数。把"能不能做"升级为"在竞争中由谁、多快、以什么可审计机制做"。**

## 0. 直觉与动机

**灵感 1（竞赛策略 → 安全不是分配，安全只是分配的约束）**
直觉：v22 的所有证书都在回答"这个计划是否可行"，却从不回答"当两个都可行的计划争同一段走廊时，谁让谁"。这正是"竞赛"的缺席：多机器人系统本质是一个**资源竞争系统**（路口、窄道、充电桩、共享工作区、边缘算力槽位），而现有 CFC++ 只做"证据是否一致"的共识，不做"资源归谁"的分配。若用临时规则（先到先得、ID 排序）分配，会同时损失**活性**（死锁）与**可审计性**（没人能证明这次让行是公平且安全的）。核心创新：**安全约束竞争机制 (Safety-Constrained Competition Mechanism, SCCM)**——先做**词典序**两段式：第一段是硬安全过滤（只保留已认证、且两两时空不冲突的计划），第二段才是机制设计（在安全集内按申报的紧迫度做 VCG 式社会福利最大化 + 外部性定价）。关键反直觉点：**安全约束与激励相容并不冲突——只要可行集由"已认证计划"而非"申报值"决定，安全就是一个与出价无关的硬约束，机制可以在这块固定地基上自由地做博弈**。谁也无法用撒谎把系统骗进不安全区，最多只能骗到更差的排序（而且 VCG 让撒谎无利可图）。

**灵感 2（边缘计算 → 证书不是名词，而是带保质期的分布式对象）**
直觉：v22 把证书当成"一旦生成就成立"的静态对象，但 50Hz 控制环里真正稀缺的是**验证算力与通信时延**：CFC++ 跨 N 机共识、能量积分、conformal 重校准不可能全在机上完成。边缘计算把"验证"变成一种**有截止期的服务**：证书必须在 `d_τ` 之前由某个边缘节点完成验证并签发**边缘背书 (Edge Attestation Certificate, EAC)**，否则它就只是一张过期废纸。核心创新：**截止期感知的边缘验证调度 (Deadline-Aware Edge Verification, DAEV)** + **边缘背书证书 (EAC)**：用 conformal 对验证时延 `L_τ(e)` 给出分布无关上界 `L^{1-ε}`，只有 `到达 + L^{1-ε} ≤ d_τ` 且背书年龄 `≤ Δ_max` 的任务才被准入；错过截止期一律**向保守退化**（本地粗检或 SafeStop），绝不"先跑起来再补验证"。关键反直觉点：**在边缘计算里，"没验证完"与"验证失败"必须被同等对待为不安全——因为控制环等不起一个迟到的'安全'**。

**灵感 3（二者的化学反应 → 边缘算力本身也是被竞争的资源）**
直觉：把前两条接起来会得到一个更锋利的观察：**边缘节点是有限的，验证槽位需要被竞争分配**。于是"竞赛策略"与"边缘计算"不是两个并列灵感，而是同一枚硬币：机器人既竞争**物理资源**（路权），也竞争**验证资源**（边缘算力/带宽）。若二者分开调度，会出现"抢到了路权却排不上验证"的诡异死锁。核心创新：**统一的稀缺资源竞争层**——把路权槽位与边缘验证槽位放进同一个**词典序安全拍卖**，先保安全、再保时效、最后保公平/吞吐。同时引入**对抗性边缘共识 (Adversarial Edge Consensus, AEC)**：`f` 个拜占庭边缘节点可能谎报验证结果或时延，故要求 `≥2f+1` 背书或跨节点中位数聚合；再引入**竞赛即证伪 (Competition-as-Falsification, CAF)**：定期举办"红队锦标赛"，让攻击者/对抗策略竞争着去找证书的反例，胜出的反例直接灌入 v22 的 `W_sim` 并触发重校准。关键反直觉点：**让机器人相互竞争，反而能比集中式规划更快暴露证书的边界——竞赛是最便宜的对抗性测试**。

**如何统一**
统一为 v22 之上的 **"稀缺性-时效性"层**：SCCM 回答"谁得到什么"，DAEV/EAC 回答"证书在何时之前还算数"，AEC 回答"边缘节点说谎怎么办"，CAF 回答"谁来发现证书错在哪"。共享状态 `ζ_pgev` 扩展为 **`ζ_comp = ζ_pgev ∪ (Π^cert, a_t, pay_t, load_e, att_t, Δ_max, f, W_red)`**。统一准入门：**HPC-C = (HPC-E, a ∈ A_safe, EAC 新鲜)** 三证一体——只有"物理能量安全 ∧ 在安全分配中胜出 ∧ 边缘背书未过期"才进入执行；任一缺失退回 v22 的保守模式，再退 v21/v20。`Exec_v23 = Exec_v22 ∩ A_safe ∩ Fresh ⊆ Exec_v22`。

## 1. 研究问题（Q12–Q15）

- **Q12（安全与激励的兼容）**：如何定义一个机制，使其输出**对任意（含对抗性）申报**都落在认证安全集 `A_safe` 内？在"可行集由已验证证书而非申报决定"的前提下，VCG 的激励相容性在多大程度上保持？机器人**策略性地隐藏/选择提交哪些已认证计划**（plan-menu manipulation）会造成多大的效率损失，能否用"证书覆盖计划菜单"或"占优策略显示"消除？
- **Q13（截止期即安全性）**：边缘验证时延的 conformal 上界 `L^{1-ε}` 需要什么交换性假设？在拥塞突变、对抗负载、节点异构下如何在线检测分布漂移并触发重校准？"错过截止期"与"验证失败"如何统一为保守退化，且不引入控制环的抖动（迟滞/滞回如何设计）？
- **Q14（拜占庭边缘与鲁棒聚合）**：`f` 个拜占庭边缘节点下，如何把 `≥2f+1` 背书、跨节点中位数、以及"证书密码学绑定"三者组合成鲁棒聚合？对抗节点能否通过**谎报低时延**骗取准入？鲁棒性与活性（可用背书数）的权衡边界在哪里？
- **Q15（在线竞争与遗憾）**：在机器人到达序列对抗性未知的在线设定下，安全分配算法的**福利遗憾**与**安全遗憾**分别是什么量级？"安全线性 bandit / 约束在线学习"能否给出 `O(√(T N log N))` 的福利遗憾且安全遗憾恒为 0？红队锦标赛的"证伪收益"如何量化并回灌到证书重校准？

## 2. 设计原则（在 P41–P42 基础上新增 P43–P47）

**P43 竞争不越安全界（Competition-Within-Safety）**
机制 `M` 的值域被硬约束在 `A_safe(t) = {a : ∀i, π_i(a) ∈ Π_i^cert(t) ∧ 两两时空不冲突}` 内。申报只改变目标函数权重，不改变可行集；`a = M(b) ∈ A_safe` 对**任意** `b` 成立。故 `Exec_v23 = Exec_v22 ∩ A_safe ∩ Fresh ⊆ Exec_v22`。当 `A_safe = ∅`，触发**可审计的保守默认**（按可验证状态排序 + 其余 SafeStop），绝不静默死锁。

**P44 截止期即证据时效（Deadline-as-Evidence-Freshness）**
计划 `π` 仅当存在边缘节点 `e` 满足 `arrival(τ_π) + L^{1-ε}_τ(e) ≤ d_τ` 且 `EAC.age ≤ Δ_max` 时准入。"未在截止期内验证" ≡ "验证失败" ≡ 不安全；一律向保守退化。过期背书不可被任何"事后补验证"追认。

**P45 诚实报告激励相容（Incentive-Compatible Truthfulness）**
在已验证的证书菜单 `{Π_i^cert}` 固定时，紧迫度维度的 VCG 分配使"如实申报"为占优策略；支付 = 该机器人造成的**安全外部性**（对他人福利的边际影响）。**计划菜单操纵**不被安全过滤放大（最多降低效率，不能制造不安全），并在审计链中显式记录申报与证书的差异。

**P46 边缘失效向保守（Edge-Failure Conservative Monotonicity）**
任一边缘节点失效/分区/时延膨胀，只会**移除**可准入任务（`A_safe` 收缩、`Fresh` 收紧），绝不新增。拜占庭节点无法伪造安全（证书密码学绑定 + `≥2f+1` 背书）；其最坏影响是降低活性，而非放宽安全。

**P47 竞赛即证伪（Competition-as-Falsification）**
定期红队锦标赛：攻击方竞争寻找使证书失效的反例 `(π, u)`，胜出反例进入 `W_red ⊆ W_sim`；任一非空 `W_red` 使相关证书的 `HPC-C` 立即失效并触发重校准。**找不到反例 ≠ 已证明**（沿用 v22 `W_sim = ∅` 的语义），竞赛只提供证伪证据、不提供证明。

## 3. 与基线的接口（如何退化）

- SCCM 失效（机制求解器崩溃）⇒ 退回 v22 的 CFC++ 共识 + 静态让行规则（按 ID/能量裕度）⇒ `A_safe` 更保守 ⇒ 子集；
- DAEV 失效（时延界不可信）⇒ 所有任务按"未验证"处理 ⇒ 本地粗检 + 全局限速 ⇒ 比 v22 更保守；
- EAC 缺失/过期 ⇒ 该计划不可准入 ⇒ 收缩；
- AEC 无法满足 `2f+1`（背书不足）⇒ 退回单节点但**强制降级**为"仅在非共享区可用" ⇒ 子集；
- CAF 发现反例 ⇒ 相关证书失效 ⇒ 收缩（方向恒为保守）；
- 全失效 ⇒ 完全回退 v22 ⇒ `Exec_v23 ⊆ Exec_v22 ⊆ Exec_v21 ⊆ Exec_v20`。

## 4. 预期贡献

1. **安全约束机制设计**：首次把"多机器人资源竞争"形式化为"硬安全集上的机制设计"，证明安全可行集与申报解耦后，VCG 激励相容与碰撞安全可同时成立，`Exec_v23 ⊆ Exec_v22` 闭环；
2. **截止期即安全性**：把边缘验证时延的 conformal 上界纳入准入门，给出"未验证完 = 不安全"的严格语义，堵住"迟到的安全证书"这一新失效面；
3. **边缘背书与拜占庭鲁棒**：EAC（密码学绑定 + 时延证明）+ `2f+1`/中位数聚合，使对抗性边缘节点只能降低活性、不能放宽安全；
4. **安全遗憾为零的在线分配**：给出约束在线学习视角下的福利遗憾上界与恒为零的安全遗憾，量化"竞争带来的效率"与"竞争不带来的风险"；
5. **竞赛即证伪**：把红队锦标赛变成证书维护的常规机制，使对抗性测试从一次性验收变为持续的证据生成。

## 5. 本轮最大风险

**一句话**：整套方案把"边缘时延 conformal 界"当作新的地基，但时延分布在拥塞突变与对抗负载下最容易失去交换性——一旦界失效而漂移检测滞后，一张**过期但看起来新鲜**的背书就会让"竞争分配"悄悄变成"竞争冒险"，且机制对机器人策略性隐藏可行计划的防护仍不完整。

```python
# IP-436 安全约束竞争机制
@dataclass
class Bid:
    robot_id: int
    plan: Plan            # 必须是已认证计划
    cert: HPCEProof       # HPC-E 证书；验证器独立核验，不信任 bid
    urgency: float        # 申报紧迫度（可撒谎，但不影响可行性）

class SafetyConstrainedCompetitionMechanism:
    def __init__(self, verifier, conflict_oracle, solver):
        self.verify = verifier            # HPC-E 独立核验
        self.conflict = conflict_oracle   # 时空冲突判定
        self.solver = solver              # 安全集内福利最大化（ILP / 贪心+局部搜索）

    def certified_menu(self, bids):
        # 可行性只由“已验证证书”决定，与 urgency 无关
        menu = {}
        for b in bids:
            if self.verify.check(b.cert, b.plan):
                menu.setdefault(b.robot_id, []).append(b.plan)
        return menu

    def allocate(self, bids, horizon):
        menu = self.certified_menu(bids)
        A = AllocEnumerator(menu, self.conflict, horizon)   # A_safe
        if A.is_empty():
            return self.conservative_default(menu)          # 可审计默认 + SafeStop
        urg = {b.robot_id: b.urgency for b in bids}
        a_star = self.solver.max_welfare(A, urg)            # 只在 A_safe 内取解
        pay = self.vcg_payments(A, a_star, urg)             # 外部性定价
        return Allocation(a_star, pay, proof=A.witness(a_star))

    def conservative_default(self, menu):
        # 只依赖可验证状态（能量裕度、截止期余量），不依赖申报
        order = sorted(menu, key=lambda i: verifiable_priority(i))
        return Allocation(order, pay={}, mode="SAFE_DEFAULT")

    def vcg_payments(self, A, a_star, urg):
        # p_i = Σ_{j≠i} u_j(a_{-i}) − Σ_{j≠i} u_j(a*)
        out = {}
        for i in urg:
            a_wo = self.solver.max_welfare(A.without(i), {k: v for k, v in urg.items() if k != i})
            out[i] = (sum(urg[k] for k in urg if k != i and a_wo.assigns_plan(k))
                      - sum(urg[k] for k in urg if k != i and a_star.assigns_plan(k)))
        return out
```

```python
# IP-437 截止期感知边缘验证
class DeadlineAwareEdgeVerifier:
    def __init__(self, latency_calibrator, eps=1e-3):
        self.calib = latency_calibrator        # 拟合 L_τ(e) 的 conformal 分位
        self.eps = eps

    def latency_bound(self, task, node):
        # 分布无关上界：P(L_τ(e) ≤ L_hat) ≥ 1-ε（需交换性）
        return self.calib.quantile(task.class_id, node.id, 1 - self.eps)

    def admits(self, task, node, now):
        L_hat = self.latency_bound(task, node)
        arrival = max(now, node.ready_time)
        return arrival + L_hat <= task.deadline and node.capacity_ok(task)

    def schedule(self, tasks, nodes, now):
        admitted, rejected = [], []
        for t in sorted(tasks, key=lambda x: x.deadline):      # EDF 优先
            feasible = [e for e in nodes if self.admits(t, e, now)]
            if not feasible:
                rejected.append(t)                              # 未验证完 ≡ 不安全
                continue
            e = min(feasible, key=lambda e: self.latency_bound(t, e))
            admitted.append((t, e)); e.reserve(t)
        return admitted, rejected
```

```python
@dataclass
class EdgeAttestation:
    cert_root: bytes      # 被验证证书的 merkle root
    node_id: str
    issued_at: float
    latency: float
    sig: bytes
    def fresh(self, now, delta_max):
        return (now - self.issued_at) <= delta_max

def issue_attestation(cert, node, latency):
    root = merkle_root(cert.serialize())
    body = (root, node.id, time.now(), latency)
    return EdgeAttestation(*body, sig=node.sign(body))

# IP-439 对抗性边缘共识
class AdversarialEdgeConsensus:
    def __init__(self, m, f):
        self.m, self.f = m, f
        assert m >= 2 * f + 1

    def aggregate(self, attestations, deadline_for):
        groups = group_by(attestations, key=lambda a: a.cert_root)
        out = {}
        for root, atts in groups.items():
            valid = [a for a in atts if verify_sig(a)]        # 密码学绑定
            if len(valid) < 2 * self.f + 1:
                out[root] = "UNVERIFIED"; continue            # 背书不足 → 保守
            lat = median(a.latency for a in valid)            # 中位数抗谎报低时延
            out[root] = ("VALID", lat) if lat <= deadline_for(root) else "STALE"
        return out
```

```python
# IP-440 HPC-C 统一准入门（HPC-E 原样保留，只加门）
@dataclass
class HPCC:
    hpce: HPCE
    allocation: Allocation
    attestations: dict

    def admits(self, robot_id, plan, now, delta_max):
        hpce_ok = self.hpce.admits(plan, ...)                  # v22 几何∧规范∧能量
        alloc_ok = self.allocation.assigns(robot_id, plan)     # a ∈ A_safe
        att = self.attestations.get(merkle_root(plan.cert.serialize()))
        fresh_ok = (att is not None and att.status == "VALID"
                    and att.fresh(now, delta_max))
        return hpce_ok and alloc_ok and fresh_ok

# IP-441 竞赛即证伪：红队锦标赛
class CompetitiveFalsificationTournament:
    def run(self, cert_bundle, attackers, rounds):
        witnesses = set()
        for _ in range(rounds):
            for atk in attackers:
                pi, u = atk.propose(cert_bundle)               # 攻击方竞争找反例
                if cert_bundle.violated(pi, u):
                    witnesses.add((pi, u))
            if witnesses:
                break
        return witnesses   # 非空 → W_red ⊆ W_sim → 相关证书失效 → 重校准
```

## 2. 关键推导与定理

**定理 1（安全继承）**：对任意申报剖面 `b`（含对抗性），`M(b) ∈ A_safe(t)`，因此 `Exec_v23 ⊆ Exec_v22`。
*证明*：`certified_menu` 独立核验 HPC-E，`A_safe` 由已验证计划与冲突约束定义，均与 `b.urgency` 无关；`allocate` 只在 `A_safe` 内取解，`conservative_default` 也只取已认证计划。故任一输出计划都通过 HPC-E 且两两不冲突，逐机器人落在 `Exec_v22_i` 中。□

**定理 2（紧迫度维度激励相容）**：当证书菜单 `{Π_i^cert}` 固定时，SCCM 的 VCG 分配使如实申报 `urgency` 为占优策略。
*证明要点*：由定理 1，可行集与类型申报无关，问题退化为标准 VCG 环境；支付等于外部性，标准论证给出 DSIC。□
*边界*：**计划菜单操纵**（隐藏/替换已认证计划）不在本定理覆盖范围；P45 要求审计链记录"申报计划集 vs 证书计划集"的差异。其最坏后果是效率损失，而非安全破坏（仍受 `A_safe` 硬约束）。

**定理 3（截止期安全，条件性）**：若边缘时延样本满足交换性，则被准入的背书满足 `P(验证于 d_τ 前完成) ≥ 1-ε`。
*证明*：conformal 分位保证 `P(L ≤ L^{1-ε}) ≥ 1-ε`；准入规则强制 `arrival + L^{1-ε} ≤ d_τ`。□
*失效模式*：交换性破坏（拥塞突变 / 对抗负载）→ 界失效 → 必须由漂移检测器触发保守退化；否则定理不成立。这正是本轮最大风险的来源。

**定理 4（边缘失效单调）**：节点失效、分区或时延膨胀只会使 `admitted` 收缩，`A_safe` 与 `Fresh` 单调收缩，绝不扩张。
*证明*：`admits` 对节点可用性单调递增、对时延上界单调递减；移除节点只减少候选，时延膨胀只抬高 `L^{1-ε}`。结合定理 1 得 `Exec_v23` 单调不增。□

**定理 5（遗憾）**：安全遗憾 `Regret_safe(T) = 0`；福利遗憾 `Regret_w(T) = O(ρ·√(T N log N))`（约束在线学习标准界 × 组合近似因子 ρ）。
*证明思路*：安全由每轮硬投影到 `A_safe` 保证；福利部分把"仅可选安全集"视为动作集受限的 bandit，对 UCB/EXP3 的标准分析给出界，组合求解器近似引入乘子 ρ。□

**命题 6（拜占庭边界）**：当拜占庭节点数 `f ≤ (m-1)/2` 时，`AEC` 的 `VALID` 判定不被对抗节点单方面翻转；对抗节点只能通过拒绝背书降低活性。
*证明要点*：中位数在 `≥ f+1` 个诚实值中取中，`f` 个任意值无法移动中位数越过真实值的 `f+1` 阶次；证书与 `cert_root` 密码学绑定，伪造需破坏签名。□

## 4. 与基线的闭环

`Exec_v23 = Exec_v22 ∩ A_safe ∩ Fresh`，其中 `A_safe` 只收缩（定理 1）、`Fresh` 只收紧（P44/P46），`W_red ≠ ∅` 亦只令证书失效。因此任意组合失效方向恒为保守：SCCM→v22 静态让行、DAEV→本地粗检、AEC→非共享区降级、CAF→证书失效，全部 `⊆ Exec_v22`。

**本轮最大风险（一句话）**：全部保障最终依赖"边缘时延 conformal 界在分布漂移下仍有效"这一统计假设——而漂移检测与重校准之间天然存在窗口期，窗口内"过期却看似新鲜"的背书可能把竞争分配变成竞争冒险。
