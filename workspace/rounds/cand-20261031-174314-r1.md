# 第 13 轮（新循环 R1）· X-FACT：用「物体功能帧 + 动作契约」把跨物体泛化和容错控制焊进单模型

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。按状态文件延续编号为第 13 轮，按本轮新灵感词循环为 R1。三个词是「**跨物体泛化**」「**伦理与合规**」「**容错控制**」。本轮不推倒第 12 轮 CHUNK-SERVO，而是在它上面加两层：**X-FACT（功能帧 + 动作契约）负责“对着什么做、做到什么算对”**，**FTE（容错执行器）负责“做偏了怎么发现、怎么回来”**；合规则从附录提到设计约束，用单 checkpoint、确定性监控、安全包络和审计日志来“自证”。

## 0. 先给结论：榜首不到 30%，但真正的可攻击面是两个 20%

先纠正一条本轮复核到的关键事实：**截至 2026-10-31，官网 `/leaderboard.html`、`/runs.html` 和首页都显示 “Coming Soon”，但 `/leaderboard_data.json` 仍返回旧的 8 模型数据**。这份 JSON 的 `generated_from` 是 `gen_leaderboard.py`；对 8 模型 ×32 任务做 `step_score ~ success_rate` 回归，`R² > 0.9999996`、最大残差 <0.006；8 个模型的 32 维任务成功率两两平均相关只有 **0.0975**；256 个任务成功率里只有 **1 个**是 10% 的整数倍（真实 10 次 trial 只能是 0/10、1/10、…、10/10）。所以：

- 用户说的“榜首不到 30%”与预览 JSON 一致（MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%），但**这不是可复现的实测 SOTA，只是赛事方的难度/预览信号**。
- 这不影响本轮判断，反而强化了它：**头部模型的真实路线是公开的，分数不是**。我们分析路线，不把预览任务排名当难度表。
- 更重要的是，规则把 5 类泛化各放 2/10：位置、干扰物、背景、**未见物品**、**人为干扰**。后两类各占全部 320 trials 的 **20%**，而且恰好是当前 VLA 最不擅长、又最容易被工程化解决的两类。

本轮的核心判断：

> 榜首不到 30% 不是“模型不够大”，而是三个缺口叠在一起：
> **物体功能帧缺失**（没见过/换了外观就不知道抓哪里、放哪里）、
> **动作契约缺失**（不知道“现在应该到哪”，只能等下一个 chunk 或到最后才发现失败）、
> **故障恢复缺失**（成功演示里没有失败，单模型规则又不允许再加一个学习恢复器）。
> 跨物体泛化和人为干扰各 20%，正好对应这三个缺口；合规不是扣分项，而是让这套东西能被官方接受、能稳定跑完 320 trials 的前提。

所以本轮押注 **X-FACT**：

> 用官方 WLA 做 30 步语义规划；用 33k 条成功演示**自监督**出「抓取功能帧 G」和「放置功能帧 P」；让同一个 checkpoint 的辅助头预测功能关键点与动作契约；运行时用契约残差检测“抓空/滑移/卡住/物体被移动/延迟异常”，用确定性恢复库和 5 步视觉伺服把任务拉回来；所有动作先过安全包络。**单模型、无第二个学习策略、可审计。**

一句话：**把“跨物体”从外观问题变成功能帧对齐问题，把“容错”从再训一个恢复模型变成契约残差 + 确定性执行器问题。**

## 1. 本轮新核实的事实（只列会改变方案的）

**对方案的约束**：不从预览榜单的任务排名里挖创新点；只从公开模型家族路线、官方规则/数据/API 里挖。跨物体和人为干扰的 20% 权重来自**规则**，不是来自榜单。

### 1.2 规则：5 类泛化各 2/10，跨物体与人为干扰各 20%（A）

官方参赛手册（中文/英文，2026-10-31 通过 `r.jina.ai` 复核）明确：

- 所有任务须基于**同一模型**完成，不得混合多个模型；模型类型不限（World Model、VLA 均可）。
- 32 个任务，每任务 10 次独立运行；5 类泛化各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
- 单次真机执行上限 **180 s**；排名先看 32 任务总平均成功率，相同看总平均步骤分，再相同看更早提交。
- 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态必须隔离。
- 另有**不计分的单任务测试通道**，可用于单任务 A/B。
- 官方会记录每步延迟、波动和动作统计规律，作为结果可信度的一部分。

**算术**：每类泛化全局 `2/10 = 20%`，即 **64/320 trials**。若未见物品轴 +15pp，全局约 **+3.0pp**；人为干扰轴 +15pp，再 **+3.0pp**；两项叠加的保守目标 **+4–6pp**。这不是承诺，是投资组合的上限估计；必须用配对 A/B 和重复实验证明。

### 1.4 API：四路 RGB、无深度/力/触觉，chunk 内不重看世界（A）

提交模板当前 main（commit `edd0a1c9`，2026-08-21）给出：

- 观测：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB 480×640；双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str`。
- 动作：`joint` 或 `ee` 互斥；`action_chunk_size` 固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action`。
- `obs_delta_indices` 决定传哪些键、堆叠几帧；`image_resize` 可缩放；`meta.token` 每次都要带。
- **没有 depth、camera_info、force/torque、tactile。**
- README §6 明确：评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分。

**关键推论**：`chunk=30 @30Hz` 是 **1 秒开环**；chunk 内没有新观测，也没有打断机制。跨物体/人为干扰/接触故障都发生在 chunk 内，所以必须把执行块降下来（CHUNK-SERVO 的 5 步），并让契约监控在块边界做决策。

**版本注意**：网上有些旧文档/缓存页显示 `data_keys`/`obs_chunk_size`，当前 main 是 `obs_delta_indices`/`image_resize`。以提交仓库当前 main 为准；提交前再 diff 一次。

### 1.5 官方基座：WLA 6B 已开源，算力不是主要瓶颈（A）

- **UnifoLM-WLA-1.0**：6B 参数，约 **2,500 h** 真机数据，**64** 个任务（桌面 + 全身），支持二指夹爪和五指灵巧手；2026-09-28 开源 Base 权重与微调代码。
- 动作专家默认 **`chunk_size=30`、`target_fps=30`**，覆盖约 `[0, 29/30]` 秒；默认 4 步扩散去噪。
- 微调默认冻结 VLM（`qwen_vl_interface`），只训 DiT action head + robot-state projector；**单张 24GB GPU** 可跑；仓库支持 **LoRA** 微调。
- 统一动作空间 **54 维**，统一状态 **60 维**；EE/base pose 用相对 SE(3) 表示；状态用绝对位姿 + rot6D。

**战略结论**：不要从零训 6B/14B。把官方 WLA 当基座，把省下的算力投到**功能帧/契约/容错执行器**——这些是当前公开基座没有覆盖的层。

## 2. 诊断：三个缺口，不是三个模型

把一次失败拆开：

```text
t0: 观测 → VLA 推理 (100-300ms) → 返回 30 步 chunk
t0+0.1s: evaluator 开始执行 chunk
t0+0.1s … t0+1.1s: 机器人开环执行 30 步
        ↑ 抓空/滑移/卡住/人移动物体都发生在这一段
t0+1.1s: 才看到下一帧 → 已经晚了
```

在此之上，本轮的三个新缺口：

1. **物体功能帧缺口**：VLA 的视觉表征偏向训练物体外观；未见物品（不同颜色/形状/材质）会改变抓取点、接近方向、放置姿态。没有显式的“功能接触点/受器帧”，模型只能靠语义先验猜。
2. **动作契约缺口**：VLA 输出的是动作，不是“当前应该达到的相对位姿”。成功演示里其实隐含了契约（抓取时夹爪相对物体的位姿、放置时物体相对受器的位姿），但没有被显式建模；失败只能等下一个 chunk 或最后 rubric 才发现。
3. **故障恢复缺口**：训练数据全是成功轨迹；单模型规则禁止再加一个学习恢复器；API 没有力/触觉；180 s 超时。于是“抓空后重抓”“卡住后回退”“人移动物体后重定位”都没有系统化处理。

合规缺口是第四个，但它是约束不是分数：单模型、延迟可信度、安全、数据许可、审计。把它做好，才能让前三个缺口的工程被官方接受。

## 3. 方法：X-FACT

### 3.1 总架构

```text
                    ┌──────────────────────────────────────────┐
                    │ Evaluator (N ports 8765..8765+N-1)       │
                    └───────────────┬──────────────────────────┘
                                    │ websocket: obs / action chunk
                                    ▼
        ┌──────────────────────────────────────────────────────┐
        │ Per-port PolicyService (CPU)                         │
        │  ├─ contract monitor (X-AC)                          │
        │  ├─ fault-tolerant executive (FTE)                   │
        │  ├─ safety envelope (X-SAFE)                         │
        │  ├─ 5-step visual servo (CHUNK-SERVO)                │
        │  └─ action adapter (WLA 54D → API 21D)               │
        └───────────────────────┬──────────────────────────────┘
                                │ async, batched
                                ▼
        ┌──────────────────────────────────────────────────────┐
        │ Shared VLA server (GPU, one checkpoint)              │
        │  ├─ frozen VLM + DiT action head (30-step plan)      │
        │  ├─ auxiliary functional-keypoint head (X-KP)        │
        │  └─ auxiliary contract head (X-AC)                   │
        └──────────────────────────────────────────────────────┘
```

- **唯一学习模型**：一个 checkpoint；辅助头与动作头共享 backbone/训练，不是第二个模型。
- **确定性层**：契约监控、恢复库、安全过滤，无学习权重。
- **数据资产**：33k 成功演示 → 功能帧、契约统计、关键点伪标签；不是第二个策略。
- **数字孪生**：只做标定/故障注入/恢复库调参，不训大模型。

### 3.2 功能帧（FOF）

对每个任务，从成功演示里定义两个功能帧：

- **抓取功能帧** `G = T_O^E(t_g)`：抓取时刻夹爪相对被操作物体的位姿。它编码“抓哪里、从哪个方向接近、夹爪怎么开合”，与物体外观无关。
- **放置功能帧** `P = T_R^O(t_r)`：释放时刻物体相对受器的位姿。它编码“放到哪、以什么姿态接触/插入/挂住”，与物体外观无关。

在线用头部双目/腕部图像估计 `T_B^O(t)`、`T_B^R`、`T_B^E(t)`，则：

```math
e_g(t) = \operatorname{Log}\!\left(G^{-1}\,(T_B^O(t))^{-1}T_B^E(t)\right),
\qquad
e_p(t) = \operatorname{Log}\!\left(P^{-1}\,(T_B^R)^{-1}T_B^O(t)\right).
```

- `e_g → 0`：夹爪已到功能抓取帧。
- `e_p → 0`：物体已到功能放置帧。
- 对插入任务，把 `e_p` 分解为轴向 `e_ax` 和横向 `e_lat`；横向先收敛，再进轴向。

**为什么这能跨物体**：换了一个杯子，只要“把手/杯沿/受器钩子”的功能几何还在，`G`、`P` 仍然有效；外观变化由 VLA 的语义/关键点头处理，不由控制层记忆。**为什么这能容错**：`e_g/e_p` 是“现在偏了多少”的直接度量，不依赖最后 rubric。

### 3.3 动作契约（X-AC）

从成功演示的每个阶段标定契约：

```math
d_k(t)=\sqrt{e_k(t)^\top \Sigma_k^{-1} e_k(t)},
\qquad
\text{contract satisfied}\iff d_k(t)\le \theta_k.
```

- `k`：阶段（接近/抓取/搬运/对位/插入/释放）。
- `Σ_k`：该阶段残差在成功演示上的鲁棒协方差（MAD/截尾）。
- `θ_k`：成功演示的 95 分位（可加 20% 裕度）。
- 连续 `m=3` 帧超阈值，或阶段超时 `τ_k`，触发故障。

契约不是“精确轨迹”；它是**带容差的相对位姿包络**。这样既不会把正常的多模态执行判死，又能在“抓空/卡住/物体被移动”时给出明确信号。

### 3.4 自监督功能关键点（X-KP）

不手工标关键点。用机器人自己的成功演示当标注器：

1. 用夹爪开合 + 物体-夹爪相对运动检测 **grasp event** 和 **release event**。
2. 在 grasp 帧，把头部双目点云变换到 base 系，取夹爪中心附近 2–3 cm 的点簇，最近点/簇中心即**抓取接触点**；腕部图同时给 2D 热图标签。
3. 在 release 帧，取物体与受器接触处的点簇，即**放置接触点**；受器平面/轴向由局部点云拟合。
4. 用 `recomputed_ee_valid=1`、重投影误差、夹爪宽度一致性做质量过滤；多 episode 投票去噪。
5. 训练一个轻量关键点/热图头，与 action expert 联合；推理时与动作头共享 backbone。

这样得到的不是“物体类别标签”，而是**功能接触点**；对未见物体，关键点头根据几何/语义预测“该抓哪里”，契约再用相对位姿验证。

### 3.5 跨物体泛化的四个机制

| 机制 | 做什么 | 不做什么 |
|---|---|---|
| **功能帧对齐** | 把动作/目标表达在 `G`、`P` 上；换物体时只换帧，不换策略 | 不假设物体 CAD/6D 位姿网络 |
| **功能关键点** | 自监督接触点 + 辅助头；跨任务共享“抓/放”功能 | 不按物体类别训分类器 |
| **跨任务功能混合** | 对共享抓/放原语的任务（杯/碗、插头/网线、试管/药瓶）做功能帧对齐后的动作块混合，增加“同功能、不同几何”的组合 | 不做无验证的图像合成；不把外观混合当几何泛化 |
| **外观/背景/干扰物增强** | 颜色、纹理、光照、背景替换、干扰物插入；腕部 ROI 局部对齐 | 不把“换个颜色”当成未见物品的全部 |

**优先级**：先做功能帧 + 关键点（直接命中 20% 轴），再做跨任务混合（数据效率），最后做外观增强（低成本兜底）。

### 3.6 容错执行器（FTE）

故障分类与恢复库：

| 故障 | 检测信号 | 恢复动作 | 终止条件 |
|---|---|---|---|
| **F1 目标/功能帧** | 关键点置信度低、`e_g` 不降、物体跟踪丢失 | 重观察 R1 → 重锚定 R2 → 同模型重规划 R5 | 2 次或 10 s |
| **F2 抓取** | 夹爪宽度与物体宽度不符、`r_grasp` 突变、物体不随夹爪动 | 张开 → 后退 5 cm → 重抓 R3 → 验证宽度 | 2 次或 8 s |
| **F3 对位/接触** | `e_p` 平台、`e_lat` 不降、关节跟踪误差/动作饱和 | 沿插入轴后退 2 cm → 腕部 IBVS 重对位 R4 → 慢插 | 2 次或 12 s |
| **F4 人为/环境** | `edit_score` 高、物体帧跳变、意外遮挡 | 停 → 等人/场景稳定 R6 → 重定位 R2 → 重规划 R5 | 3 s 等待 + 1 次 |
| **F5 接口/延迟** | RTT 超阈、观测陈旧、动作形状/NaN 异常 | 保持 → 降 chunk/降分辨率 → 重规划 | 立即；连续 3 次则 R7 |
| **F6 安全** | 关节/工作空间/自碰撞/人距超限 | 安全停 → 后退 → 重规划；不可行则 R7 | 安全优先，无重试上限 |

恢复选择用确定性规则表 + 经验成功率查找表，不用学习策略：

```math
R^\*=\arg\min_R \left[c_{\text{time}}(R)+\lambda c_{\text{safety}}(R)-\beta \hat P_{\text{success}}(R\mid f,k)\right].
```

`\hat P` 来自仿真/离线扰动统计，是一个查表，不是在线学习模型。

### 3.7 安全与合规层（X-SAFE / X-COMP）

**安全包络**：每个 chunk 先过确定性过滤器：

- 关节位置/速度/加速度限幅；EE 工作空间盒；桌面高度；自碰撞胶囊距离；人距 keep-out。
- 6 维 EE 速度 QP：`min ||u-u_vla||² s.t. A u ≥ b`；不可行则 hold/abort。
- 人距用头部双目深度 + 运动/前景检测；不引入行人检测模型。近 0.4 m 降速，近 0.25 m 让步。
- 最小侵入：正常时过滤器是恒等映射；只在危险时投影，避免“安全税”把成功率打下去。

**合规自证**：

- **单 checkpoint**：所有头在同一个 `model.safetensors`；启动时哈希，所有端口日志记录同一哈希；无 per-task 权重、无模型切换。
- **无第二学习模型**：监控/恢复/安全都是确定性；恢复库是有限技能；关键点/契约头与动作头联合训练，属于同一模型。
- **数据合规**：只用公开 `unibot-v1-challenge-dataset`（Apache-2.0，署名）；不用测试视频/榜单数据；不训练时泄漏。
- **隐私**：审计日志只存哈希/ROI 统计；如保存视频，人脸打码；不重分发人体图像。
- **透明**：模型卡、失败分类、审计日志、复现脚本；提交材料写清楚“单模型”的边界。
- **公平**：不做 test-time 遥操作、不重放录像、不探测 evaluator、不按任务切模型。

### 3.8 与 CHUNK-SERVO / FACT-VLA / GEO-RESIDUAL 的关系

- **保留**：CHUNK-SERVO 的 30 步规划 + 5 步伺服、演示检索、数字孪生标定；FACT-VLA 的相位化 BC、柔顺执行、证据门控；GEO-RESIDUAL 的动作条件化残差、米制表面距离、编辑检测。
- **升级**：GEO-RESIDUAL 的残差 → 功能帧契约残差；演示检索 → 功能帧/关键点；5 步伺服 → 契约触发的恢复；合规从附录 → 设计约束。
- **剪枝**：不再从零训 VLA/World Model；不做完整 sim-to-real 策略训练；不做第二个学习恢复器；不做 6D 物体位姿网络；不做力/触觉（API 没有）；不做 32 个任务各一个策略；不把预览榜单当难度表。

## 5. 竞赛策略：两个 20% 是主战场，但不要一次铺 32 个任务

### 5.1 任务分档（先验，待单任务通道更新）

- **S 档（跨物体 + 容错双高，先做 5 个）**：HangCup、PlugInEthernet、StackBowls、ArrangeTestTubes、ZipUp。
- **A 档（容错/安全高，第二批）**：Unlock、SyringeWaterTransfer、ToolboxStorage、StorePaddle、PackPhone、OrganizeStationery。
- **B 档（跨物体/分类为主）**：FruitSorting、ColorArrangement、OrganizeTools、StoreEarphones、PaperCupStacking。
- **C 档（变形/长程，只做回归保护）**：FoldTowel、PackBag、PackDoll、SpellRobot；契约只用于夹爪/受器，不用刚体物体帧。

### 5.2 单任务通道协议

1. 选 5 个 S 档任务；每任务 5 次 A/B（X-FACT on/off）；同初始条件。
2. 指标：成功率、步骤分、耗时、p99 延迟、恢复次数、安全违规。
3. 通过：至少 3/5 任务 +10pp；C 档不回归 >5pp；无安全违规。
4. 再扫 `H_c ∈ {3,5,8}`、关键点头 on/off、契约 on/off、恢复 on/off。
5. 通过后才跑 32×10 正式评测；不拿正式 320 trials 做未验证的 A/B。

### 5.3 收益算术（保守）

- 未见物品轴 +15pp → 全局 +3.0pp。
- 人为干扰轴 +15pp → 全局 +3.0pp。
- 其他轴（位置/干扰物/背景）因功能帧/局部 ROI 各 +3–5pp → 全局 +1.8–3.0pp。
- 合计保守 +4–6pp，乐观 +7–9pp；但 320 trials 的 SE 约 2.4pp，必须配对/重复，不能拿 +1–2pp 当结论。

## 6. 本轮明确不做（剪枝）

- 不从零训 VLA/World Model（官方 WLA 已开源，算力不划算）。
- 不做完整 sim-to-real 策略训练（只做契约/恢复/安全的风洞）。
- 不做第二个学习模型/残差策略/学习 verifier（单模型风险）。
- 不做 6D 物体位姿网络（透明/变形不可靠；用功能帧 + 局部几何）。
- 不做力/触觉闭环（API 没有）。
- 不做 32 个任务各一个策略（规则禁止）。
- 不把预览榜单当难度表/SOTA（已证伪）。
- 不做无验证的图像级物体合成（物理/几何不一致会教坏策略）。
- 不做 test-time 遥操作/录像重放/evaluator 探测（伦理与合规红线）。

## 2. 问题形式化

### 2.1 评分与泛化轴

总分：

```math
S=\frac{1}{32}\sum_{t=1}^{32}p_t,\qquad
p_t=\frac{1}{10}\sum_{j=1}^{10}y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

5 类泛化各 2/10，因此每类全局权重：

```math
w_{\text{axis}}=\frac{2}{10}=0.2,\qquad
N_{\text{axis}}=320\times 0.2=64\ \text{trials}.
```

若未见物品轴提升 `Δu`、人为干扰轴提升 `Δh`，全局近似：

```math
\Delta S\approx 0.2\,\Delta u+0.2\,\Delta h+\sum_{\text{other axes}}0.2\,\Delta a.
```

320 trials 下，`p≈0.25` 的单次标准误：

```math
\mathrm{SE}(S)\approx\sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

单轴 64 trials 的 SE 约 `0.054`；5 次/任务的 A/B 只能看方向，不能看显著性。

### 2.2 功能帧

记 `T_B^A` 为“A 在 B 中的位姿”（把 A 坐标映射到 B）。对一条成功演示 `ξ`：

- 抓取时刻 `t_g`：

```math
G_\xi=T_{O(t_g)}^{E(t_g)}=\left(T_B^{O(t_g)}\right)^{-1}T_B^{E(t_g)}.
```

- 释放时刻 `t_r`：

```math
P_\xi=T_{R}^{O(t_r)}=\left(T_B^{R}\right)^{-1}T_B^{O(t_r)}.
```

在线估计 `T_B^O(t)`、`T_B^R`、`T_B^E(t)`，则：

```math
e_g(t)=\operatorname{Log}\!\left(G_\xi^{-1}\left(T_B^O(t)\right)^{-1}T_B^E(t)\right),
```

```math
e_p(t)=\operatorname{Log}\!\left(P_\xi^{-1}\left(T_B^R\right)^{-1}T_B^O(t)\right).
```

`e_g=0` 表示夹爪到功能抓取帧；`e_p=0` 表示物体到功能放置帧。对插入任务：

```math
e_{ax}=a^\top e_p,\qquad
e_{lat}=(I-aa^\top)e_p,
```

其中 `a` 是受器插入轴（受器帧下的单位向量）。先收敛 `e_lat`，再进 `e_ax`。

**可辨识性条件**：

1. 功能帧在头部双目或腕部视野内；
2. 双目 ROI 有效像素 ≥70%，或腕部特征 inlier ≥15；
3. 相机标定重投影 ≤5 px；
4. 功能帧估计协方差低于阈值；
5. 任务属于刚体接触类（S/A 档）；变形任务只对夹爪/受器使用契约。

任一条不满足 → 回退 VLA 开环或检索式相对目标；不硬做。

### 2.3 动作契约

对阶段 `k`（接近/抓取/搬运/对位/插入/释放），从成功演示收集残差 `{e_k^{(i)}}`，估计鲁棒均值 `μ_k` 和协方差 `Σ_k`（MAD/截尾），并定义：

```math
d_k(t)=\sqrt{(e_k(t)-\mu_k)^\top\Sigma_k^{-1}(e_k(t)-\mu_k)}.
```

阈值：

```math
\theta_k=\operatorname{Quantile}_{0.95}\!\left(\{d_k^{(i)}\}\right)\times(1+\eta),\qquad \eta=0.2.
```

契约满足 `d_k(t)≤θ_k`；连续 `m=3` 帧超阈，或阶段耗时 `>τ_k`，触发故障。`τ_k` 取成功演示该阶段时长的 1.5 倍（上限 30 s）。

**为什么用 Mahalanobis 而不是欧氏**：不同轴（横向/轴向/旋转）尺度不同；协方差白化后可用一个阈值，且对正常多模态更宽容。

### 2.4 故障检测统计

定义 hazard：

```math
h(t)=w_g d_g(t)+w_p d_p(t)+w_s r_{\text{slip}}(t)+w_e \text{edit}(t)+w_l \text{lat}(t).
```

- `r_slip`：夹爪闭合时，物体-夹爪刚体运动残差；突变 → 滑移。
- `edit`：GEO-RESIDUAL 的场景编辑分数；机器人动作解释不了的场景运动。
- `lat`：RTT/观测新鲜度异常。

故障判定用滑窗 + 迟滞：

```text
if d_k(t) > θ_k for m consecutive frames:
    if e_g not decreasing and gripper closed: F2
    elif e_p plateau and contact phase: F3
    elif edit > θ_e: F4
    else: F1/F3 by phase
elif latency stale or action malformed: F5
elif safety constraint violated: F6
```

离线在成功/扰动回放上算 AUROC、误报率、检测延迟；真机只在单任务通道验证。

### 2.5 安全约束

对 EE 速度 `u∈R^6`，定义安全集：

```math
\mathcal{S}=\{u\mid A u\ge b\}.
```

约束来源：

- 工作空间盒：`p+Δ t u_p∈[p_min,p_max]`。
- 桌面平面：`p_z≥z_table+margin`。
- 自碰撞胶囊：`h_i(q)≥0`，线性化 `∇h_i^\top J(q)u≥-γ h_i`。
- 人距球：`h_h(p)=||p-c_h||^2-r_h^2≥0`，`∇h_h^\top u≥-γ h_h`。
- 关节限位：`q+Δ t J^{-1}u∈[q_min,q_max]`。

最小侵入 QP：

```math
u^\*=\arg\min_{u}\ \|u-u_{\text{vla}}\|^2
\quad\text{s.t.}\quad A u\ge b.
```

不可行 → `u=0`（hold），然后重观察/安全 abort。正常时 `u*=u_vla`，不产生“安全税”。

**人距代理**：头部双目深度 + 前景/运动检测；用 URDF 投影排除机器人自身；近 0.4 m 降速 50%，近 0.25 m 让步（hold/retreat）。不引入行人检测模型。

### 3.2 数据管线：从成功演示到功能帧/契约

**契约统计**：对每个任务/阶段，收集 `e_g/e_p` 的残差，计算 `μ_k/Σ_k/θ_k/τ_k`；按 session/物体/背景分组划分，避免相邻帧泄漏。

### 3.3 模型与训练

**基座**：UnifoLM-WLA-1.0-Base，冻结 VLM；DiT action head + state projector 可训；可选 LoRA。

**辅助头**：

- **X-KP**：轻量热图 decoder，输入 VLM/DiT 的中间特征，输出头部/腕部功能关键点热图 + 置信度。
- **X-AC**：一个小 MLP/Transformer head，输入动作头的 hidden state + 当前相位，输出 `e_g/e_p` 的预测（或直接输出契约参数），用于在观测不完整时做短期预测；运行时仍以几何估计为主，预测只做置信度融合。

**损失**：

```math
\mathcal{L}=
\mathcal{L}_{\text{action}}
+\lambda_{\text{kp}}\mathcal{L}_{\text{kp}}
+\lambda_{\text{contract}}\mathcal{L}_{\text{contract}}
+\lambda_{\text{cons}}\mathcal{L}_{\text{cons}}.
```

- `L_action`：官方 flow-matching/diffusion 损失。
- `L_kp`：热图 MSE + soft-argmax 位置损失 + 置信度 BCE。
- `L_contract`：`e_g/e_p` 的 Huber 损失（用演示统计归一化）。
- `L_cons`：动作条件一致性——预测的动作块应该降低契约残差；用有限差分/可微 SE(3) log 实现，或只做 stop-gradient 的辅助监督。

**训练阶段**：

1. **P1 动作头微调**：官方 WLA 冻结 VLM，32 任务数据；建立基线。
2. **P2 关键点/契约头**：冻结动作头，训练辅助头；用演示标签。
3. **P3 联合微调**：小学习率联合；可选 LoRA；监控动作成功率不回归。
4. **P4 合规导出**：合并所有头到一个 checkpoint；哈希；跑单模型 attestation。

### 3.4 推理/控制伪代码

```python
class XFactPolicy:
    def get_action(self, obs):
        self._tick(obs)
        self._maybe_request_plan(obs)

        # 1) 功能帧/契约
        state = self.perception.estimate(obs)          # T_B_O, T_B_R, T_B_E, conf
        contract = self.contract.evaluate(state)       # d_g, d_p, phase, conf

        # 2) 故障检测 + 恢复
        fault = self.monitor.classify(contract, state, obs, self.plan_age)
        if fault != F0:
            self.recovery.enter(fault, contract, state)

        # 3) 规划/伺服
        if self.plan is None:
            self.plan = self.vla.predict(obs)          # cold start / replan
            self.plan_idx = 0

        if self.mode == "SERVO" and self.goal is not None:
            a_ff = self.plan[self.plan_idx:self.plan_idx + self.H_c]
            delta = self.servo.compute(obs, self.goal) # 5-step IBVS/PBVS
            a_cmd = compose_relative(a_ff, delta)
        else:
            a_cmd = self.plan[self.plan_idx:self.plan_idx + self.H_c]

        # 4) 安全包络
        a_safe = self.safety.filter(a_cmd, obs)        # QP / clamp / hold

        # 5) 推进
        self.plan_idx += self.H_c
        if self.plan_idx >= len(self.plan):
            self.plan = None
        return self.adapter.to_api(a_safe, obs, self.token)
```

`_maybe_request_plan`：

```python
def _maybe_request_plan(self, obs):
    if self._future is not None and not self._future.done():
        return
    if self._future is not None:
        self.plan = self._future.result()
        self._future = None
    if self.plan is None or self.plan_age >= self.plan_ttl:
        snapshot = copy_obs(obs)
        self._future = self.executor.submit(self.vla.predict, snapshot)
```

规则：

- VLA 永远不阻塞 `get_action`（除冷启动）；plan 过期就用旧 plan + 契约/伺服。
- 每个 chunk 只做一次契约评估 + 一次伺服；失败不影响返回合法动作。
- 任何异常 → 返回上一组合法 chunk 或安全 hold；绝不返回 NaN/错误形状。

### 3.6 恢复库

| ID | 技能 | 前置 | 动作 | 成功条件 | 预算 |
|---|---|---|---|---|---|
| R1 | Re-observe | 任意故障 | 退到安全观察位（桌面上方 20 cm），腕部朝向工作区，等 0.2 s | 功能帧置信度 ≥ 阈值 | 3 s |
| R2 | Re-anchor | F1/F4 | 重估 `T_B^O/T_B^R`，更新契约，保持当前夹爪状态 | 残差回到阈值内 | 2 s |
| R3 | Re-grasp | F2 | 张开 → 后退 5 cm → 到抓取点 → 闭合 → 验证夹爪宽度 | 宽度在物体宽度 ±20% | 8 s |
| R4 | Re-align | F3 | 沿插入轴后退 2 cm → 腕部 IBVS 对位 → 低速插入 | `e_lat` 降到阈值内 | 12 s |
| R5 | Re-plan | F1/F3/F4 | 用同一 VLA + 恢复 prompt（“regrasp the cup from the handle”等）+ 当前观测重规划 | 新 plan 合法 | 5 s |
| R6 | Yield | F4/F6 | 停/后退，等人/场景稳定（最多 3 s），再 R1/R2 | 场景稳定 | 3 s |
| R7 | Safe abort | 任意，安全优先 | 退到安全位，张开夹爪，结束 episode | 安全位到达 | 5 s |

选择规则（确定性）：

```text
if fault == F6: R7/R6
elif fault == F2: R3 -> R5 -> R7
elif fault == F3: R4 -> R5 -> R7
elif fault == F4: R6 -> R2 -> R5 -> R7
elif fault == F1: R1 -> R2 -> R5 -> R7
elif fault == F5: hold -> degrade -> R5 -> R7
```

每次故障最多 2 次恢复；总恢复时间 ≤ episode 的 20%；超预算 → R7。恢复期间契约监控继续；如果恢复动作使残差变差，立即停止。

### 3.7 动作适配（WLA 54D → 挑战赛 21D）

```text
WLA 54D:
  left_ee_rel[6], left_gripper[1], left_hand[6],
  right_ee_rel[6], right_gripper[1], right_hand[6],
  waist[3], torso[3], base_vxvy[2], base_wz[1],
  base_pose_rel[6], height[1], left_leg[6], right_leg[6]

挑战赛 ee 21D:
  left_ee_abs[6], right_ee_abs[6],
  left_gripper[1], right_gripper[1], pivot[7]
```

映射：

1. `left_ee_abs = compose(T_base_ee_left_current, exp(left_ee_rel))`；转 xyz+rpy。
2. `right_ee_abs` 同理。
3. gripper 直通（按挑战赛的 0–1 方向校验）。
4. `pivot = [vx, vy, wz, yaw, pitch, roll, height]`，从 WLA base/waist 组合；具体符号/顺序用 `example_env.py` 和单任务通道验证；不确定时先零 pivot。
5. 腿部/灵巧手在 `ee` 模式下不直接下发；若 `pivot` 需要下身体，按官方 WLA server 的 `action.pivot` 语义映射。

**关键细节**：WLA 的每个未来动作是“相对 plan-time 当前 EE”的位姿，不是累积增量；adapter 必须先把整个 30 步 compose 成 base 系绝对目标，再按 5 步切片。否则第 6–30 步会以错误锚点解释，产生系统性偏移。

**帧/TCP 风险**：WLA 的 EE 帧与挑战赛 `*_ee_pose_gripper_base` 可能差一个 TCP/夹爪长度偏移；必须用 `example_env.py` 和真实数据做一次手眼/工具坐标校准（平移 ≤1 cm、旋转 ≤2°）。这是 G7 的第一验证项。

## 4. 跨物体泛化

### 4.1 功能帧对齐

以 HangCup 为例：

- 训练物体：某种杯子 + 某个杯架。
- 未见物体：不同颜色/形状/材质的杯子。
- `G` 定义在“把手/杯沿”的功能接触点；`P` 定义在“杯架钩子”的受器帧。
- 换杯子时，`G` 不变（只要把手几何在）；`P` 不变（受器没变）；VLA/关键点头负责把 `G`  ground 到新杯子的把手上。
- 如果新杯子没有把手，关键点头应预测“杯沿/杯壁”的可行抓取点；契约的 `G` 需要多模态（每个任务存多个 `G` 模板，运行时选置信度最高的）。

**多模态功能帧**：每个任务可从演示聚类出 K 个抓取模式（把手、杯沿、杯壁）；运行时用关键点头/点云几何选一个；契约分别评估。这样不会把“另一种正确抓法”误判为故障。

### 4.2 跨任务功能混合

对共享功能原语的任务对：

| 原语 | 任务对（示例） | 可混合的帧 |
|---|---|---|
| 圆柱抓取 | HangCup / StackCups / StoreCups / ArrangeTestTubes / PourOutMedicine | `G`（夹爪相对圆柱） |
| 插入 | PlugCharger / PlugInEthernet / ArrangeTestTubes | `P`（轴向 + 横向） |
| 叠放 | StackBowls / PaperCupStacking / ArrangePlates | `P`（支撑面 + 中心） |
| 挂钩 | HangCup / StorePaddle / StoreEarphones | `P`（钩/环） |

**混合方式**：在功能帧对齐后，把源任务的动作块变换到目标任务的功能帧，和目标任务的视觉观测配对；用一致性过滤（功能帧误差 ≤1 cm/5°、动作速度/加速度在限内）剔除不一致样本。**不做像素级物体替换**，避免物理/几何不一致。

### 4.3 外观/几何增强

- 颜色/亮度/对比度/色调抖动；背景替换（桌面纹理）；干扰物插入（从其他任务物体抠图/合成）。
- 尺度/姿态扰动（在功能帧内）；腕部 ROI 随机裁剪。
- 几何增强只做“小范围、可验证”的缩放/旋转；不做大幅形状变形（会破坏功能帧）。
- 对透明/反光物体：不用颜色增强，改用边缘/深度/轮廓；契约置信度低时回退。

### 4.4 失败模式

| 失败 | 典型任务 | 该投什么 | 不该投什么 |
|---|---|---|---|
| 新物体抓取点错 | HangCup、StackBowls、StoreCups | 关键点头 + 多模态 G + 重抓 | 更大 VLA |
| 新物体尺寸/宽度不符 | PlugCharger、ArrangeTestTubes | 夹爪宽度自适应 + 点云尺寸 | 固定夹爪开度 |
| 新物体放置姿态错 | StackBowls、PaperCupStacking | 受器帧 + 多模态 P + 视觉伺服 | 6D 物体位姿网络 |
| 新物体语义错（抓错物体） | FruitSorting、ColorArrangement | VLA 语义 + 关键点置信度 | 纯几何伺服 |
| 变形物体 | FoldTowel、PackBag | 只做夹爪/受器契约；VLA 主导 | 刚体功能帧 |

| 门 | 跨物体 +10pp 或失败模式改善；人为干扰恢复 ≥70% |

### 5.5 全量

| 项 | 设计 |
|---|---|
| 任务 | 32×10 |
| 端口 | N 个连续端口 |
| 指标 | 总平均成功率、步骤分、p99、timeout、内存、安全违规 |
| 门 | 无端口串扰；reset 干净；内存不涨；p99 ≤150 ms |

### 5.6 消融

1. 关键点头 on/off。
2. 契约 on/off。
3. 恢复 on/off。
4. 安全过滤 on/off。
5. 5 步 vs 30 步 chunk。
6. 功能帧 vs 绝对目标。
7. 多模态 G/P vs 单模板。
8. 跨任务混合 on/off。
9. 冻结 VLM vs LoRA。
10. 恢复预算 10%/20%/30%。

### 5.7 统计

- 320 trials，`p≈0.25`，SE≈2.4pp。
- 单轴 64 trials，SE≈5.4pp。
- 配对 A/B：McNemar / bootstrap；报告差值 CI，不只报均值。
- 5 次/任务只能看方向；不要用 +1–2pp 做结论。
- 离线指标按 session/物体/背景分组划分；相邻帧不跨 split。

## 7. 风险、合规与伦理

### 7.1 单模型合规的三种模式

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 关键点/契约只离线生成标签；线上纯 VLA + 确定性伺服 | 最低 | 保守回退 |
| C2 同 checkpoint 辅助头 | X-KP/X-AC 与动作头联合训练；一个 `model.safetensors` | 低；需向官方说明 | 主推 |
| C3 同 checkpoint 特征 | 用 VLA 同一 checkpoint 的 encoder 做关键点/描述子；不加载第二个模型 | 低–中 | 需要强特征时用 |

禁止：加载第二个学习策略/残差网络/独立视觉编码器做在线决策；test-time 遥操作；录像重放；evaluator 探测。

### 7.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 辅助头被判定为第二模型 | 取消资格 | 同一 checkpoint 联合训练；C1/C2/C3；提交前邮件确认 |
| 功能接触点标签噪声 | 契约误判/抓取偏移 | 多 episode 投票；`recomputed_ee_valid` 过滤；人工抽检 |
| 功能帧在透明/变形物体上失败 | 误报/停顿 | 只对刚体 S 档启用；腕部 2D/检索兜底；C 档关闭 |
| 契约阈值过紧 | 正常多模态被打断 | 95 分位 + 裕度；迟滞；置信度门控；只在连续超阈时触发 |
| 恢复打断成功轨迹 | 成功率下降 | 最小侵入；只在契约失败时触发；总预算 ≤20% 时间 |
| 安全过滤过度保守 | 成功率下降 | CBF 最小投影；正常时恒等；只在危险时介入 |
| 人距检测误报 | 无故停顿 | 深度 + 运动 + 尺寸 + 时序一致性；0.4/0.25 m 双阈值 |
| RTT/延迟 | 监控/恢复不及时 | 5 步 chunk；RTT 估计；降分辨率；超时回退 |
| `pivot` 语义不一致 | 动作被拒/机器人不动 | 先用 `example_env.py`/单任务通道验证；零 pivot 回退 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复；320 trials SE≈2.4pp |
| 数据许可/隐私 | 合规风险 | Apache-2.0 署名；只用公开数据；人脸打码；不重分发人体图像 |
| 多次提交限制 | 无法 A/B | 邮件确认；单任务通道先验证；一次提交则保守 |

### 7.3 伦理与合规清单

- **数据**：只用 `unibot-v1-challenge-dataset`（Apache-2.0，署名）；记录版本/哈希；不用测试视频/榜单数据；不训练时泄漏。
- **隐私**：不存原始人体图像；如需保存视频，人脸打码；不重分发人体图像；日志只存哈希/ROI 统计。
- **安全**：关节/速度/工作空间/自碰撞/人距约束；人类让步；安全 abort；ISO 10218-2:2025 的“确定性监控 + 硬约束”思想。
- **透明**：模型卡、失败分类、审计日志、复现脚本；不隐藏失败；不 cherry-pick。
- **公平**：单 checkpoint；无 per-task 权重；无 test-time 遥操作；无 evaluator 探测；无录像重放。
- **环境**：冻结 VLM/LoRA；24GB GPU；避免从零训大模型；报告算力消耗。
