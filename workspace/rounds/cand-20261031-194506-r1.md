# 第 13 轮 · JOLT：语言契约 → 桌面对象 SLAM → 关节空间伺服，把「指令里的顺序/位置/接触」变成可验证的执行

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新一轮灵感循环的第 1 轮，但状态文件已跨 12 轮保留，故编号记为第 13 轮。三个灵感词是「关节空间控制」「同步定位与建图」「语言指令」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是把它们从「观测/控制层」推进到「任务结构层」：**语言负责说清楚做什么，地图负责记住东西在哪，关节负责把最后 3 厘米做稳。**

## 0. 先给结论：榜单不到 30%，缺的不是更大的 VLA，而是三个被丢掉的结构

截至 2026-10-31，官网静态页的排行榜区域显示「即将发布 / Coming Soon」，但 `leaderboard_data.json` 仍返回 8 个预览模型：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。这些数字仍然只能当「预览上限/难度信号」：JSON 的 `generated_from` 是 `gen_leaderboard.py`，8 模型 ×32 任务的步骤分与成功率线性回归 R² > 0.999999，232/256 个成功率不是 10% 的整数倍，跨模型任务级成功率平均相关只有 0.098。**但头部模型家族的技术路线是真实的，值得分析；分数本身不可复现。**

我的判断是：所有头部方案共享的瓶颈，不是语言理解，也不是 3D 感知，而是三个没有被显式建模的「结构」：

1. **语言结构**：32 个任务、每个任务 5 条同义指令；粗筛显示 **17/32** 含多子句、**7/32** 含显式顺序、**5/32** 颜色相关、**8/32** 含数量/全称量词、**26/32** 含具体空间/容器关系（词表见产物区）。扁平 VLA 把整条指令压成一个 embedding，很容易在「先红后绿再蓝」「两个在下、一个在上」「打开拉链→放文具→拉上拉链」这类结构上失败。
2. **空间结构**：每个 action chunk 都重新估计世界，没有持久对象地图。位置泛化、遮挡、人为移动物体，都要求机器人记住「杯子刚才在哪、现在还在不在」。纯 VLA 的隐状态不是为这种米制持久记忆设计的。
3. **关节结构**：挑战赛 API 同时支持 `joint` 和 `ee`；官方 WLA 的 54 维动作里只有 EE 相对动作，**没有手臂关节槽**。7-DoF 手臂的 1 维冗余、关节限位、奇异点、以及接触时的关节跟踪误差，都被 EE 接口藏掉了。没有力/触觉传感器时，关节跟踪误差可能是最便宜的无传感器接触信号。

所以本轮的押注是 **JOLT（Joint-space Object-Language Tasking）**：

> **把 160 条指令离线编译成可验证的任务契约；用头部双目 + 本体位姿维护桌面对象地图；VLA 仍出 30 步 EE 规划，但执行层改成「解析 IK + 7-DoF 零空间 + 5 步关节伺服」；用关节跟踪误差做接触代理；契约、地图、伺服三者互相校验。**

一句话：**不是再训一个更大的 VLA，而是给现有 VLA 装上「任务语法、空间记忆、关节反射」三个确定性外挂。**

## 1. 我先重新核实了什么（只列会改变判断的）

### 1.1 榜单：静态页「即将发布」，JSON 仍是 8 个预览模型

- 官网首页/挑战赛页/排行榜页在 2026-10-31 的静态 HTML 都显示排行榜「即将发布 / Coming Soon」；但 `leaderboard_data.json` 仍可读到 8 个模型和 32 个任务的完整数据（直接 `curl` 会撞上 WAF 挑战页，本轮通过 `r.jina.ai` 渲染代理读取）。
- JSON 的 `generated_from` 是 `gen_leaderboard.py`；我们的回归与相关性分析仍是上一轮的结论：步骤分是成功率的线性缩放，不是实测；成功率出现 27.29%、38.43% 等非 10% 整数倍；8 个模型的 32 维任务成功率两两平均相关仅 0.098。
- **结论**：不把 29.7% 当 SOTA，不把任务级排名当难度表；只从「头部模型家族公开路线」和「官方规则/数据/API」里挖创新点。榜单静态页的变化也可能意味着正式评测/榜单正在重置，这对竞赛策略的含义是：**先交可复现基线，再谈冲榜。**

### 1.2 规则：单模型、32 任务、10 次/任务、5 类泛化各 2 次、180 s、N 端口

官方参赛手册（2026-10-31 复核中文版，`r.jina.ai` 抓取）仍明确：

- 所有任务须基于**同一模型**完成，不得混合多个模型；模型类型不限（World Model、VLA 均可）。
- 32 个任务，每个任务 10 次独立运行；5 类泛化各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
- 单次真机执行上限 **180 s**；排名先看 32 任务总平均成功率，再看向总平均步骤分，再看向更早提交。
- 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态必须隔离。
- 另有**不计分的单任务测试通道**，可用于单任务成功率/步骤分验证。

**对 JOLT 的约束**：地图、契约、关节伺服都必须是每端口独立、CPU 轻量、不抢 GPU 的确定性模块；VLA 仍是唯一学习模型；单任务通道是唯一敢做 A/B 的地方。

### 1.3 API：`joint` 模式是新的开放变量，且没有深度/力/触觉

提交模板 README（2026-10-31 复核）给出：

- 观测：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640**；双臂关节 `left_arm/right_arm [7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str`。
- 动作：`control_space` 仅 `"joint"` 或 `"ee"`，二者互斥；`joint` 模式返回 `action.left_arm/right_arm [7]`（目标关节位置），`ee` 模式返回 `action.left/right_ee_pose_gripper_base [6]`（绝对目标位姿，xyz+rpy）。
- 共享动作：`action.left_gripper [1]`、`action.right_gripper [1]`、`action.pivot [7]`。
- `action_chunk_size` ≥1，固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action`；**chunk 内没有新观测，也没有打断机制**。
- **没有 depth、camera_info、force/torque、tactile**；评测端逐调用记录延迟、波动和动作统计规律。
- 控制频率未在 README 写死；本轮仍假设 30 Hz（与数据 30 fps 一致），必须在单任务通道实测。

**关键推论**：`joint` 模式不是一个无关紧要的选项，而是把「解析 IK / 关节限位 / 零空间 / 接触跟踪误差」从 evaluator 手里拿回到策略侧的唯一接口。EE 模式把 IK 交给 evaluator，策略看不到关节级接触信号；joint 模式则相反，策略要自己保证可执行性。**这是一个可 A/B 的架构分叉，不是实现细节。**

### 1.4 数据：33,276 eps / 169.28 h；每个任务 5 条同义指令；关节和 EE 动作都有

32 个 HF 数据集（2026-10-31 逐数据集读取 `meta/info.json`）合计：

| 项 | 数值 |
|---|---:|
| episodes | **33,276** |
| frames | **18,282,246** |
| 时长 | **169.28 h**（30 fps） |
| 任务数 | 32 |
| 单任务 episodes | 969–1,533 |
| 单任务平均时长 | 6.2 s（HangCup）–37.6 s（ToolboxStorage） |

数据里同时有：

- `observation.state.left_arm/right_arm [7]` 与 `action.left_arm/right_arm [7]`：**绝对关节位置**，30 Hz；关节顺序 `shoulder_pitch, shoulder_roll, shoulder_yaw, elbow, wrist_yaw, wrist_roll, wrist_pitch`。
- `observation.state.left/right_ee_pose_gripper_base [6]` 与 `action.left/right_ee_pose_gripper_base [6]`：EE 绝对位姿，xyz+rpy。
- `action.lower_body [15]`、`action.pivot [7]`、`action.base_command [4]`、`action.action_torso [6]`、`action.waist_action_joint [3]`：下身体/腰部/躯干命令。
- 四路视频：`head_stereo_left/right`、`wrist_left/right`，均 480×640；头部双目有完整内参、畸变、R/T、基线 **58.2526 mm**、`rectified: true`；腕部相机也有 color/IR 内参及 IR→color 外参（`camera_params.wrist_left/right`），但**只有 RGB/IR，没有深度**。
- **语言**：每个数据集的 `meta/tasks.parquet` 只有一行，但包含 **5 条同义指令**，用 `@` 分隔。例如 HangCup：`Hang the cup on the marked spot on the cup rack.@Hang the cup on the marked position...@Hook the cup...`。评测端是逐 trial 轮换 5 条、还是只用其中一条，README 未说明；但这是现成的同义鲁棒性测试集。

我粗扫了 32 条主指令（取每条的第一句）：

- **17/32** 含逗号、`and` 或 `then` 的多阶段/多子句结构；
- **7/32** 含显式顺序/序列词（`right to left`、`in the order`、`one by one`、`then`、`from ... to ...`）；
- **5/32** 含颜色约束（显式颜色词，或 `matching color`）；
- **8/32** 含数量/全称量词（`all`、`each`、`every`、`two`、`three`、`one`）；
- **26/32** 含具体空间/容器关系（`on`、`into`、`inside`、`in front`、`aside`、`upright`、`rack`、`box`、`bag`、`shelf`、`case`、`port`、`socket`、`board`、`table`、`conveyor`）。

这不是语义标注，只是关键词粗筛；但它足以说明：**语言不是装饰，而是任务结构的一部分。**

我做了一个最小验证（B）：**只用每个任务第 1 条指令训练、其余 4 条同义指令测试**，字符 3-gram 最近邻的任务识别是 **119/128 = 93.0%**；错误集中在 `DisconnectEthernet`/`PlugInEthernet`、`PackBag`/`OrganizePencilCase`、`ZipUp`/`OrganizePencilCase` 等语义相邻任务，正好由契约的动作极性（insert/remove）、对象角色（source/target/tool）区分。这说明在线任务识别不需要第二个模型，一个字符 n-gram 索引 + 少量极性规则就够用；剩余误差是契约 schema 的用武之地，而不是 VLA 的。

### 1.5 官方 WLA：54 维动作没有手臂关节槽，这正好留下一个空位

官方 `unifolm-wla` 文档（2026-10-31 复核）明确：

- 54 维动作里，`[0:6]` 左 EE（相对当前 EE 的 xyz + rotvec）、`[13:19]` 右 EE；`[26:29]` 腰、`[29:32]` 躯干、`[32:35]` base 平移/旋转、`[35:41]` base 相对位姿、`[41:42]` 高度、`[42:54]` 双腿。
- **没有手臂 7 关节的动作槽**；手臂只能通过 EE 相对动作表达。
- 默认 `chunk_size=30`、`target_fps=30`，覆盖约 `[0, 29/30]` 秒；默认 4 步扩散去噪。
- 6B 参数，约 2,500 h 真机数据，64 个任务；微调时冻结 VLM，只训 DiT action head + robot-state projector，单张 24GB GPU 可跑。

**战略含义**：官方基座已经把「大模型 + EE 动作」做完了；挑战赛的 `joint` 模式是它没有覆盖的接口。我们可以选择：

1. 保持 WLA 的 EE 规划，自己做解析 IK + 关节伺服（不改模型，最快落地）；
2. 把 WLA 的 EE action head 换成关节 action head，用 33k 演示微调（同一 checkpoint，仍是单模型，但工程更重）。

本轮主推 1，保留 2 作为后续。

### 1.6 头部方案：都是 EE/chunk 路线，没人显式做「任务契约 + 持久地图 + 关节接触」

榜单名字对应真实公开模型家族（分数是预览；路线是公开材料摘要，未逐项复核）：

| 模型家族 | 公开路线 | 优势 | 本轮相关瓶颈 |
|---|---|---|---|
| **MolmoAct2** | Ai2 的 action reasoning model；Molmo 2-ER + 专用 action expert + adaptive depth reasoning；强调 3D 空间推理与推理加速 | 3D/空间语义强；双臂 | 仍是 EE/action chunk 开环；最后插入/挂/拉链的接触精度与恢复 |
| **WALL-OSS-0.5** | X Square 的 4B 级 VLA（VLM + action expert）；公开材料称在自建真机任务上 average progress 明显高于基线（具体数值未逐项复核） | 预训练直接可用；progress 高 | progress ≠ success；最后一步失败就 0 分；4B 实时性 |
| **DreamZero** | 公开材料称 14B 级 Wan video-diffusion world-action model；预测未来视频再出动作 | 长程预测/规划 | 14B 推理重；世界模型不直接解决毫米级对齐；1 秒 chunk 更危险 |
| **π0.5** | 开放世界泛化 VLA | 语义/新场景泛化 | 接触密集任务精度；远程部署延迟 |
| **GigaBrain-0** | 世界模型生成数据 + VLA | 数据效率/泛化 | 生成数据物理保真度；最后 3 厘米 |
| **GR00T N1.5** | NVIDIA 通用人形 VLA | 生态/embodiment | 任务特定精度；数据覆盖 |

共同点：公开路线大多以 **EE 动作 + 开环 chunk** 为主；公开材料里没有看到把「关节空间接触闭环」和「语言契约 + 持久对象地图」同时作为核心的模型。JOLT 的切口就在这里。

### 1.7 近期工作：混合 VLA + 经典原语是热点，但组合还没人做

- **Harness VLA**（arXiv 2607.08448，摘要级）：冻结 VLA + 小型解析原语库 + 记忆增强 agent；在 LIBERO-Pro/RoboCasa365 上相对最强基线 +38.6/+25.4 pp。说明「VLA 只做接触段、其余交给确定性原语」是有效的；但它用 LLM coding agent 做高层编排，和本赛「单模型 + 远程 API」约束不同。
- **SkipVLA**（arXiv 2609.20648，摘要级）：VLA + 经典运动规划器，自由空间用规划器，接触段才查 VLA；思想相近，但重点是运动规划，不是桌面对象地图/关节伺服。
- **Hi-VLA 系统研究**（arXiv 2606.10267，摘要级）：高层 VLM planner + 低层 VLA executor；说明分层有效，但高层仍是学习模型，带来延迟和单模型合规风险。
- **VLA 综述**（arXiv 2607.06706，摘要级）：明确指出 joint-space 动作「直接控制但 embodiment-specific」，EE 动作「便于跨本体但引入 IK 误差」。这正是本轮 joint vs EE 的 trade-off。
- **UMR**（arXiv 2609.34256，摘要级）：统一世界-自车动作表示，强调异构数据统一；反向说明「纯关节空间」不利于跨本体，但本赛只有 G1 一个本体，关节空间的代价小。
- **CompCPZ**（arXiv 2608.17717，摘要级）：把自然语言编译成集合代数约束，处理「A 或 B」的多模态指令；验证了「语言→约束」路线，但它是几何约束编译器，不是 32 任务契约 + 对象地图。
- **Object SLAM**（arXiv 2509.21602，摘要级；以及 2026 年地图管理综述）：对象级 SLAM 用语言先验约束物体尺寸/朝向，提升稀疏观测下的鲁棒性；本轮的 TO-SLAM 只借它的「对象级因子图」思想，不做完整导航 SLAM。

**结论**：混合 VLA + 经典模块是 2026 年的前沿，但「语言契约 + 桌面对象 SLAM + 关节空间伺服」这个三件套，还没有人为 UniBot 这种「固定桌面、四路 RGB、无深度、无力觉、单模型、远程 API」的场景做过。

## 2. 诊断：三个「结构」而不是三个「模型」

### 2.1 语言结构：VLA 把指令压成一个向量，但任务是有语法的

看几条真实指令：

- `Place the plates on the rack from right to left in the order of red, green, and blue.`
- `Stack the paper cups in front of you with two on the bottom and one on top.`
- `Open the pencil case zipper, place all stationery items into the pencil case, and close the zipper.`
- `Pick out the batteries from the blocks and place them into the green box.`
- `Transfer water from the large cup to the small cup using a syringe.`

这些不是「一个目标物体 + 一个放置点」的简单映射，而是：

- **有序序列**（red → green → blue；right → left）；
- **数量/结构**（two bottom + one top）；
- **多阶段**（unzip → place all → zip）；
- **选择/排除**（batteries from blocks；不要把 blocks 放进去）；
- **工具使用**（syringe 吸水/注水；key 开锁）；
- **关节物体**（zipper、lock、cap、frame）；
- **空间关系**（on the rack、into the bag、upright、aside）。

扁平 VLA 可以在一条指令上碰巧做对，但没有显式的「当前子目标/下一个子目标/是否满足」状态。JOLT 的语言契约就是把这个状态显式化。

### 2.2 空间结构：每个 chunk 重新看世界，但没有「世界在哪」的记忆

- 位置泛化：目标物体/放置区移动，VLA 需要重新定位；
- 干扰物：多余物体进入视野，VLA 可能抓错；
- 人为干扰：人把物体移走/移动，VLA 的下一个 chunk 才可能发现；
- 遮挡：机器人自己的手臂/夹爪挡住目标，单帧视觉无法恢复；
- 长程任务：ToolboxStorage 平均 37.6 s，涉及多个工具和锁；VLA 的隐状态不是米制地图。

TO-SLAM 的作用不是「建整张桌子」，而是维护**少量任务相关对象的米制锚点 + 协方差**：杯子、杯架、网口、试管架、拉链头、锁孔、药瓶、注射器、盒子。它让伺服知道「目标在哪」，让契约知道「当前该抓谁」，让人为干扰检测知道「什么东西动了、是不是我动的」。

### 2.3 关节结构：EE 接口把接触信号藏掉了

- G1 手臂 7-DoF，6D EE 任务 → 1 维零空间；不同演示可能用不同肘/腕姿态完成同一 EE 轨迹。EE 动作不指定零空间，evaluator 的 IK 可能选到关节限位/奇异点附近。
- `joint` 模式直接给 7 个关节目标，策略可以显式优化：
  - 关节限位裕度；
  - 可操作度 `sqrt(det(JJ^T))`；
  - 与演示姿态的接近程度；
  - 左右臂自碰撞/交叉。
- 没有力/触觉，但 `q_cmd - q_meas` 是关节级跟踪误差；当夹爪/工具顶住物体时，跟踪误差会上升。EE 模式看不到这个量；joint 模式看得到。它不能替代力传感器，但可以作为**接触/滑移的代理信号**，用于降低法向增益、触发回撤/重抓。

### 2.4 为什么三个词是一件事

```text
语言指令
  │  编译成契约：对象、属性、顺序、阶段、成功谓词
  ▼
任务契约 ──► 选择当前子目标/对象锚点
  │
  ▼
桌面对象 SLAM ──► 维护 T_base_target、协方差、是否被人移动
  │
  ▼
关节空间伺服 ──► IK + 零空间 + 5 步闭环 + 跟踪误差接触代理
  │
  ▼
契约验证 ──► 成功/失败/重规划
```

语言决定「跟踪谁」，地图决定「它在哪」，关节决定「怎么碰到它」。三者缺一，另外两个都会退化：

- 没有语言契约：地图不知道跟踪哪个对象，伺服不知道当前子目标；
- 没有地图：契约的对象引用没有米制落点，伺服的相对目标退化成绝对坐标；
- 没有关节伺服：地图/契约再准，最后 3 厘米仍是 EE 开环。

## 3. JOLT 方法

### 3.1 LANG-CONTRACT：把 160 条指令编译成 32 份任务契约

**离线**（开发期，不在评测时跑）：

1. 从 32 个数据集的 `meta/tasks.parquet` 读出 32×5 条指令；
2. 用规则模板 + 人工校对（可选离线 LLM 辅助）生成 32 份 JSON 契约；
3. 契约字段：`task_id`、`objects`（类别/属性/数量）、`target`、`order`、`phases`、`success`、`constraints`、`deformable`、`tool`；
4. 用 160 条指令做覆盖率/一致性测试；
5. 把契约作为静态配置文件随提交包分发。

**在线**（评测时，确定性、毫秒级）：

1. 归一化输入语言（小写、去标点、同义词）；
2. 规则抽取属性/顺序/数量；
3. 与 32 份契约做关键词/模糊匹配，得到 `task_id` 和置信度；
4. 置信度低 → 只用 VLA，不强行套契约；
5. 契约输出当前阶段和当前目标对象，供地图/伺服使用。

**示例**：

```json
{
  "task_id": "ArrangePlates",
  "objects": [
    {"role": "source", "class": "plate", "count": 3,
     "attributes": {"color": ["red", "green", "blue"]}}
  ],
  "target": {"class": "rack", "relation": "on"},
  "order": [
    {"attribute": "color", "sequence": ["red", "green", "blue"]},
    {"attribute": "position", "sequence": ["right", "middle", "left"]}
  ],
  "phases": [
    "pick(red)", "place(right)",
    "pick(green)", "place(middle)",
    "pick(blue)", "place(left)"
  ],
  "success": [
    "all(plate, on(rack))",
    "order_match(color, [red, green, blue])",
    "order_match(position, [right, middle, left])"
  ],
  "constraints": ["do_not_place_block_on_rack"],
  "deformable": false
}
```

**为什么这不是第二个模型**：契约是离线生成的静态配置；在线只做字符串匹配和规则抽取，没有学习权重，没有第二个 checkpoint。即使离线用了 LLM 辅助，它也只是开发工具，不进入提交包的推理路径。

### 3.2 TO-SLAM：桌面对象级滑动窗口因子图

不做完整 SLAM（不建整张地图、不做回环、不做稠密重建）。只做：

- **相机位姿**：离线用 `state_d435`；在线用 `lower_body[-3:]`（腰 3 关节）+ G1 URDF 正运动学恢复头部相机位姿；每机器人一次外参标定。
- **对象锚点**：对任务相关对象，用头部双目 + 桌面平面 + 局部点云做位姿估计；已知物体用演示重建的模板/尺寸先验，未知物体用语言属性 + 颜色/边缘分割。
- **因子图**：滑动窗口 30 帧；因子包括双目重投影、桌面平面、对象尺寸先验、时序平滑、机器人运动先验；用 Gauss-Newton/Levenberg-Marquardt 在 CPU 上 5–10 Hz 优化。
- **数据关联**：语言锚点（契约里的对象）+ 几何门控 + 颜色/ORB + 时序一致；新对象出现则新建锚点。
- **扰动检测**：优化后计算每个对象的运动残差；如果对象动了、夹爪不在附近、且机器人动作解释不了，标记为外部编辑，触发重定位/重规划。
- **输出**：`M_t = {object_id, label, pose, covariance, extent, status}`；伺服用 `T_base_target` 和协方差，契约用 label/status，恢复模块用 `status=moved/lost`。

**为什么这不是第二个模型**：因子图是几何估计器，没有学习权重；对象分割用经典颜色/边缘/深度，不用 SAM/CLIP 等第二个网络；如果需要语义特征，用 VLA 同一 checkpoint 的 encoder（C3 合规模式）。

### 3.3 J-SERVO：解析 IK + 7-DoF 零空间 + 5 步关节伺服

**输入**：VLA 的 30 步 EE 相对规划、地图的 `T_base_target`、契约的当前阶段、当前关节 `q`。

**步骤**：

1. 把 VLA 的相对 EE 动作 compose 成 base 系绝对目标 `T_base_ee^d`（第 12 轮已做）；
2. 用阻尼最小二乘 IK 求 `q*`：
   `Δq = J^T (J J^T + λ^2 I)^{-1} e`，`e = log(T_ee(q)^{-1} T_ee^d)`；
3. 零空间优化：
   `q_cmd = q* + (I - J^+ J) (q_N - q*)`；
   `q_N` 选择最大化可操作度、最大化关节限位裕度、最接近演示姿态；
4. 关节伺服：
   `q_{t+1} = q_t + Δt (J^+ (v_d + K_p e) + N k_n (q_N - q_t))`；
   限幅 `|q_{t+1}-q_t| ≤ Δq_max`，限加速度/ jerk；
5. 接触代理：
   `c_t = ||q_cmd - q_meas||`；
   如果 `c_t > μ + 3σ` 且 `(q_cmd-q_meas)·v_cmd > 0`，判定接触/受阻；
   接触段降低法向增益、保留切向，触发回撤/重抓；
6. 失败回退：IK 无解/接近奇异/关节限位 → 回退 EE 模式或 VLA 开环。

**为什么是 5 步**：5 步 @30 Hz = 167 ms；含 RTT 端到端约 200–320 ms；足够 1–2 次接触修正，又不会让 VLA 推理成为瓶颈。`H_c` 仍要在单任务通道扫 3/5/8。

### 3.4 与 CHUNK-SERVO 的接口

```text
VLA:   每 30 步产出一个 30 步 EE plan（后台线程，不阻塞 get_action）
契约:  每个 chunk 检查当前阶段/下一个对象
地图:  每步更新对象锚点；每 5 步给伺服一个目标位姿
伺服:  每 5 步做一次 IK + 零空间 + 关节修正
API:   metadata.action_chunk_size = 5；返回 joint 动作（7+7+1+1+7）
```

保留第 12 轮的双频结构；只是把「5 步 EE 视觉伺服」升级成「5 步关节伺服 + 地图 + 契约」。

### 3.5 合规：一个学习模型 + 三个确定性模块

| 模块 | 是否有学习权重 | 在线是否运行 | 合规说明 |
|---|---|---|---|
| VLA（WLA/自训） | 是（唯一） | 是 | 唯一学习模型 |
| LANG-CONTRACT | 否 | 是（字符串匹配） | 静态配置 + 规则，不是模型 |
| TO-SLAM | 否 | 是 | 几何估计器；不用第二个学习检测器 |
| J-SERVO | 否 | 是 | 解析 IK/控制律；无学习权重 |
| 演示检索/模板 | 否 | 是 | 查表/最近邻；不是策略模型 |

若官方对「模型」作最宽解释，走 C1/C2/C3 三种模式：C1 只离线用地图/契约标数据；C2 在线只用确定性控制器；C3 需要语义特征时用 VLA 同一 checkpoint 的 encoder。**不加载第二个学习策略/残差网络/独立视觉编码器做在线决策。**

### 5.2 单任务通道协议

1. 选 5 个代表任务：`ArrangePlates`（顺序+颜色）、`OrganizePencilCase`（多阶段+拉链）、`PickOutBatteries`（选择/排除）、`PlugInEthernet`（接触）、`FoldTowel`（变形防回归）。
2. 每个任务 5–8 次 A/B：`WLA/CHUNK-SERVO` vs `+LANG` vs `+MAP` vs `+JOINT`（逐步加，不要一次全上）。
3. 记录：成功、步骤分、耗时、p99 延迟、恢复次数、契约违反次数。
4. 通过：至少 3/5 任务 +10pp；FoldTowel 不回归 >5pp；否则不烧正式提交。
5. 再扫 `H_c ∈ {3,5,8}` 和关节/EE 模式；选 p99 与成功率的最佳折中。

### 5.3 收益算术

- 320 trials；`p≈0.25` 时单次标准误约 2.42pp；配对 A/B 会低一些，但不要声称 +1–2pp 是结论。
- 如果 LANG 让 10 个多阶段任务各 +10pp：`10/32×10 = +3.1pp`；
- 如果 MAP 让 10 个位置/干扰任务各 +10pp：`+3.1pp`；
- 如果 JOINT 让 10 个接触任务各 +10pp：`+3.1pp`；
- 三者重叠，不能直接相加；保守合计 **+4–7pp**，乐观 +8–10pp；
- 人为干扰轴占 20%；恢复 +10pp → 全局 +2pp。
- 这些是设计目标，不是承诺；G3/G7 不过就不提交。

### 5.4 提交节奏

1. **W0**：WLA + API adapter + 安全基线；单任务通道跑通 1 个任务（token/pivot/joint 顺序）。
2. **W1**：若允许多次提交，先交安全基线锁 tie-break；若只允许一次，跳过。
3. **W2–W3**：LANG-CONTRACT 离线编译 + 160 条验证；单任务 A/B。
4. **W3–W5**：TO-SLAM + J-SERVO；5 任务 A/B。
5. **W5–W6**：全量干跑 32×10；N 端口隔离；p99/内存。
6. **W6**：最终提交；保留回退开关。

# 第 13 轮产物 · JOLT 技术报告

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「JOLT」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是把它们接到「任务结构层」：**语言契约决定跟踪谁，桌面对象 SLAM 决定它在哪，关节空间伺服决定怎么碰到它。**

## 0. 结论与边界

### 0.1 一句话结论

公开头部方案大多停在「EE 动作 + 开环 chunk」；挑战赛 API 已经同时暴露 `joint` 模式和 `language`，数据里也同时有 7 关节动作、EE 动作和 32×5 条同义指令。JOLT 用**离线语言契约**把任务结构显式化，用**对象级滑动窗口 SLAM**维护米制锚点，用**解析 IK + 7-DoF 零空间 + 5 步关节伺服**执行最后 3 厘米，并用**关节跟踪误差**做无传感器接触代理。三者都是确定性模块，VLA 仍是唯一学习模型。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、排行榜 JSON 直接核实 | 32 任务/10 次/5 类泛化、joint/ee 动作、33,276 eps、5 条同义指令、WLA 54D 无关节槽 |
| B | 我们在公开数据/网页上做的分析，可复现 | 榜单 `step~success` 回归、语言匹配实验、语言结构粗筛、pivot 抽样 |
| C | 设计假设，需 G0–G8 验证 | 关节伺服 +10pp、接触代理 AUROC≥0.8、地图位姿≤10mm |

### 0.3 本轮不做什么

- 不从零训 VLA/World Model；官方 WLA 已开源 6B 基座。
- 不做完整 SLAM/回环/稠密重建；只做桌面对象级滑动窗口因子图。
- 不做学习型物体检测/分割（SAM/CLIP 等）；避免第二个模型。
- 不做第二个学习策略/残差网络；地图、契约、伺服都是确定性模块。
- 不做 6D 物体位姿网络；透明/变形物体回退 VLA。
- 不做力/触觉闭环；API 没有；只做关节跟踪误差代理。
- 不做 30 Hz 广域网伺服；用 5 步 chunk/双频。
- 不做跨 episode 记忆；规则要求 10 次独立运行。
- 不把预览榜单的任务排名当实测难度。

### 1.1 赛事规则（A）

官方参赛手册（飞书 docx，2026-10-31 通过 `r.jina.ai` 抓取；稳定拿到 §1.1–§2.2，后续章节可能截断，最终以官方页面为准）核实：

### 1.2 提交 API：joint 模式是新的开放变量（A）

提交模板 README（2026-10-31 复核）给出：

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640** |
| 本体 | 双臂关节 `left_arm/right_arm [7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str` |
| 动作空间 | `control_space` 仅 `"joint"` 或 `"ee"`，二者互斥 |
| joint 动作 | `action.left_arm [7]`、`action.right_arm [7]`：目标关节位置 |
| ee 动作 | `action.left/right_ee_pose_gripper_base [6]`：绝对目标位姿，xyz+rpy，base 系 |
| 共享动作 | `action.left_gripper [1]`、`action.right_gripper [1]`、`action.pivot [7]` |
| chunk | `action_chunk_size` ≥1，固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action` |
| token | `metadata.token` 握手校验一次；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile** |
| 监控 | 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分 |

**关键推论**：

1. `action_chunk_size=30`、30 Hz 时，一次 `get_action` 后有 **1 秒开环执行**；chunk 内没有新观测，也没有打断机制。
2. `joint` 模式把 IK/关节限位/零空间/接触跟踪误差从 evaluator 手里拿回到策略侧；`ee` 模式则相反。这是可 A/B 的架构分叉。
3. 控制频率未在 README 写死；本报告假设 30 Hz（与数据 30 fps 一致），必须在单任务通道实测。

### 1.5 榜单取证（A+B）

官网静态页（2026-10-31）首页/挑战赛页/排行榜页显示排行榜「即将发布 / Coming Soon」；`leaderboard_data.json` 仍返回 8 个模型：

| 排名 | 模型/用户 | 平均成功率 | 平均时长 | 步骤分 |
|---|---|---:|---:|---:|
| 1 | MolmoAct2 / DexHacker | **29.7%** | 44.02 s | 39.0 |
| 2 | WALL-OSS-0.5 / Generalist Robotics | 28.5% | 43.74 s | 38.9 |
| 3 | DreamZero / World Model Lab | 27.9% | 44.59 s | 37.9 |
| 4 | Spirit-v1.5 / VLAGO | 25.9% | 45.19 s | 34.4 |
| 5 | DM0 / Embodied AI Institute | 23.5% | 45.11 s | 31.7 |
| 6 | PI-0.5 / RoboReasoner | 22.8% | 43.88 s | 30.6 |
| 7 | GigaBrain-0 / xembody | 22.6% | 43.76 s | 29.5 |
| 8 | GR00T N1.5 / Humanoid Dynamics | 20.5% | 44.71 s | 28.1 |

取证分析（B）：

1. `leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`。
2. 对 8 个模型 ×32 任务做 `step_score ~ success_rate` 回归，**R² > 0.999999，最大残差 <0.006**；每个模型斜率不同，截距接近 0，形式是 `step ≈ k_model × success`。这不像独立实测的步骤分，更像脚本按模型斜率线性缩放生成；JSON 的生成来源字段也是 `gen_leaderboard.py`。
3. 8 个模型的 32 维任务成功率两两相关，**平均 off-diagonal 相关系数约 0.098**（min -0.208，max 0.353）；如果任务难度是真实的，不同模型的任务级成功率应该正相关。
4. 每任务只有 10 次 trial，但 **232/256** 个成功率不是 10% 的整数倍（如 27.29%、38.43%）；真实 10 次 trial 只能是 0/10、1/10、…、10/10。

**结论**：29.7% 可以当「预览上限/难度信号」；不能当 SOTA、任务难度表或失败分布。静态页显示「即将发布」可能意味着榜单正在重置；竞赛策略应先交可复现基线。

## 2. 问题形式化

### 2.1 评分与不确定性

总分：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

320 trials 下，若 `p≈0.25`，单次标准误：

```math
\mathrm{SE}(S)\approx \sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

配对 A/B 的方差取决于任务内相关；若同一初始条件的 A/B 成功高度相关，配对差值方差可显著降低。报告必须给配对差值的 bootstrap 置信区间，而不是只报两个平均值。

人为干扰轴：

```math
\Delta S_{\mathrm{human}} = \frac{2}{10}\,\Delta p_h = 0.2\,\Delta p_h.
```

即 human 轴成功率 +10pp → 全局 +2pp。

### 2.2 三种动作接口

| 接口 | 谁做 IK | 策略看到什么 | 优点 | 缺点 |
|---|---|---|---|---|
| `ee`（绝对位姿） | evaluator | EE 位姿、关节状态 | 与 WLA 输出兼容；跨本体 | IK 误差/奇异点不可控；接触跟踪误差看不到 |
| `joint`（绝对关节） | 策略 | 关节目标/测量 | 零空间/限位/接触代理可控 | 需要自己的 IK/标定；evaluator 控制器可能不匹配 |
| **混合（本报告主推）** | 策略 | VLA 出 EE，策略 IK→joint | 保留 WLA 语义；执行层可控 | 多一层 IK；需验证 joint 模式 |

### 2.3 语言契约

定义任务契约：

```math
\mathcal C = (\mathcal O, \mathcal A, \mathcal R, \Pi, \Phi)
```

- `O`：对象集合（类别、数量、角色：source/target/tool/distractor）；
- `A`：属性（颜色、形状、材质、状态）；
- `R`：空间/顺序关系（on、into、right-to-left、two bottom + one top）；
- `Π`：有序阶段（pick(red) → place(right) → …）；
- `Φ`：成功谓词（all(plate, on(rack))、order_match(color, [red,green,blue])）。

契约满足：

```math
\mathrm{SAT}(M_t,\mathcal C)=\bigwedge_{\phi\in\Phi}\phi(M_t)
```

其中 `M_t` 是当前对象地图。契约还给出当前阶段 `π_t ∈ Π` 和当前目标对象 `o_t ∈ O`。

### 2.4 桌面对象 SLAM

设 `T_t ∈ SE(3)` 为相机位姿，`O_i ∈ SE(3)` 为对象 i 的位姿，`x_{t,i,k}` 为对象 i 上的 3D 点，`u_{t,i,k}` 为像素观测。滑动窗口因子图：

```math
\begin{aligned}
C(T,O)=&\sum_{t,i,k}\rho\left(\left\|\pi\left(T_t^{-1}O_i x_{t,i,k}\right)-u_{t,i,k}\right\|^2_{\Sigma}\right)\\
&+\sum_t\left\|\log\left(T_t^{-1}T_{t-1}\right)-\log\left(\Delta T_t^{\mathrm{prop}}\right)\right\|^2_{\Lambda}\\
&+\sum_i\left\|\log\left(O_i^{-1}O_i^{\mathrm{prior}}\right)\right\|^2_{\Gamma}\\
&+\sum_{t,i}\rho\left(\left\|O_i(t)-O_i(t-1)\right\|^2_{\Omega}\right)
\end{aligned}
```

- 第一项：双目/多视图重投影；
- 第二项：本体（腰/头）运动先验；
- 第三项：对象尺寸/朝向先验（来自演示模板或语言常识）；
- 第四项：对象时序平滑 + 鲁棒核（人为移动时不被带偏）。

对象级扰动残差：

```math
r_i(t)=\log\left(O_i(t)^{-1}O_i(t-1)\right)
```

```math
\mathrm{external}_i(t)=\mathbb 1\left[\|r_i(t)\|>\theta_r\ \wedge\ d(\mathrm{EE},O_i)>d_{\mathrm{far}}\ \wedge\ \neg\mathrm{grasp}_i\right]
```

### 2.5 关节空间伺服

任务误差：

```math
e=\log\left(T_{ee}(q)^{-1}T_{ee}^{d}\right)\in\mathbb R^6
```

阻尼最小二乘 IK：

```math
\Delta q=J^{\top}\left(JJ^{\top}+\lambda^2 I\right)^{-1}e
```

零空间：

```math
N=I-J^{+}J,\qquad q_{\mathrm{cmd}}=q^{*}+N\left(q_N-q^{*}\right)
```

零空间目标：

```math
q_N=\arg\max_q\left[\alpha\sqrt{\det(JJ^{\top})}
-\beta\sum_i\max(0,q_i-q_i^{\max}+\epsilon)^2
-\gamma\|q-q_{\mathrm{demo}}\|^2\right]
```

伺服：

```math
q_{t+1}=q_t+\Delta t\left[J^{+}\left(v_d+K_p e\right)+Nk_n\left(q_N-q_t\right)\right]
```

接触代理：

```math
c_t=\|q_{\mathrm{cmd}}-q_{\mathrm{meas}}\|_2
```

```math
\mathrm{contact}_t=\mathbb 1\left[c_t>\mu_c+3\sigma_c\ \wedge\ (q_{\mathrm{cmd}}-q_{\mathrm{meas}})^{\top}v_{\mathrm{cmd}}>0\right]
```

反馈周期：

```math
T_{\mathrm{fb}}\approx \frac{H_c}{f_c}+\tau
```

| 场景 | `H_c` | `f_c` | `τ` | `T_fb` | 评价 |
|---|---:|---:|---:|---:|---|
| WLA 默认 | 30 | 30 | 50ms | **1050ms** | 接触段基本开环 |
| 本方案保守 | 5 | 30 | 50ms | **217ms** | 可做 1–2 次接触修正 |
| 本方案高延迟 | 5 | 30 | 150ms | **317ms** | 增益降档 |
| 低控制频率 | 5 | 10 | 50ms | **550ms** | 改 `H_c=3` 或只做 PBVS |

## 3. JOLT 系统设计

### 3.1 架构

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port JOLT Policy (CPU)         │
                    │  ├─ LANG-CONTRACT matcher/verifier  │
                    │  ├─ TO-SLAM (object factor graph)   │
                    │  ├─ J-SERVO (IK + nullspace)        │
                    │  ├─ J-PC (tracking-error contact)   │
                    │  ├─ CHUNK-SERVO plan cache          │
                    │  └─ action adapter (EE/joint → API) │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared VLA server (GPU)            │
                    │  UnifoLM-WLA-1.0 / VLA-0, 30-step   │
                    └─────────────────────────────────────┘
```

- 每个端口一个 `JoltPolicy` 实例，独立 `reset()`、独立契约状态、独立地图、独立伺服状态。
- 契约/地图/伺服是 CPU 线程，不阻塞 websocket；VLA 请求异步、可批处理。
- 共享 VLA server 用 session ID 区分端口；模型权重只有一份，不违反单模型。

### 3.2 接口契约

```python
{

    "obs_delta_indices": {
        "observation.language":                         [0],
        "observation.images.cam_left_high":             [0],
        "observation.images.cam_right_high":            [0],

    },
```

注意：

- `observation.language` 的 offset 必须是 `[0]`（标量字符串，无时间轴）。
- `joint` 模式返回 `action.left_arm/right_arm [7]` + 共享 gripper/pivot；`ee` 模式返回绝对 EE 位姿。
- 挑战赛 `ee` 动作是**绝对目标位姿**；WLA 输出的是**相对当前 EE** 的 xyz+rotvec。adapter 必须先 compose 到当前 EE 绝对位姿，再切片。
- WLA 的每个未来动作是「相对 plan-time 当前 EE」的位姿，不是累积增量；必须先把整个 30 步 compose 成 base 系绝对目标，再按 5 步切片。否则第 6–30 步会以错误锚点解释，产生系统性偏移。
- `pivot` 的 7 维语义在 README 中只写「Lower-body / pivot target」，没有逐维定义；先用 `example_env.py` 和单任务通道验证；若语义不匹配，先返回任务常数 pivot（抽样 HangCup 为 `[0,0,0,0,0.15,0,0.74]`），只验证双臂。

### 3.3 `get_action` 伪代码

```python
class JoltPolicy:
    def get_action(self, obs):
        self._tick(obs)

        contract = self.contracts.match(obs["observation.language"])
        self.map.update(obs, contract)
        self._maybe_request_plan(obs)

        if self.plan is None:
            self.plan = self.vla.predict(obs)   # 冷启动同步；超时则安全保持
            self.plan_idx = 0

        contract.update(self.map)
        if contract.violated(self.map):
            self._recover(obs, contract)

        target = contract.current_target(self.map)
        ee_chunk = self.plan[self.plan_idx : self.plan_idx + self.H_c]
        q_chunk = self.servo.solve(ee_chunk, obs, target)

        if self.contact.detect(obs, q_chunk):
            q_chunk = self.servo.contact_mode(q_chunk)

        self.plan_idx += self.H_c
        if self.plan_idx >= len(self.plan):
            self.plan = None

        return self.adapter.to_api(q_chunk, obs, self.token)
```

`_maybe_request_plan`：

```python
def _maybe_request_plan(self, obs):
    if self._future is not None and not self._future.done():
        return
    if self._future is not None:
        self.plan = self._future.result()
        self._future = None
        self.plan_idx = 0
    if self.plan is None or self.plan_age >= self.plan_ttl:
        snapshot = copy_obs(obs)
        self._future = self.executor.submit(self.vla.predict, snapshot)
```

规则：

- VLA 永远不阻塞 `get_action`（除冷启动）；plan 过期就用旧 plan + 伺服。
- 每个 chunk 只做一次伺服；伺服失败不影响返回合法动作。
- 任何异常 → 返回上一组合法 chunk 或安全 hold；绝不返回 NaN/错误形状。

### 3.4 状态机

```text
INIT ──first obs──▶ PLAN ──plan ready──▶ SERVO
  ▲                   ▲                    │
  │                   │                    ├─ contract phase done ──▶ NEXT
  │                   │                    │
  │                   │                    ├─ contact proxy ──▶ CONTACT
  │                   │                    │                 │
  │                   │                    │                 └─ released ──▶ SERVO
  │                   │                    │
  │                   └── replan ◀── RECOVER ◀── map residual / contract violation
  │                                      │
  └──────────────────────────────────────┘
任意状态 ──task success / max steps──▶ DONE
```

- `SERVO`：正常接近，地图目标 + 关节伺服。
- `NEXT`：契约当前阶段完成，切到下一个对象/阶段。
- `CONTACT`：J-PC 触发；法向增益降低、切向保留；滑移则重抓。
- `RECOVER`：地图残差/契约违反；先停，再重定位；目标可见 → 更新锚点；不可见 → VLA 重规划。
- `DONE`：任务成功/最大步数；清理状态，等待 `reset()`。

### 4.3 运行时匹配

**离线**：

1. 从 32×5 条指令中取每条的第一句作为“种子”；
2. 用字符 3-gram 余弦相似度建立 32 个种子的索引；
3. 可选：加入极性/动词规则（insert vs remove；open vs close；pack vs unpack）。

**在线**：

```text
l = normalize(obs.language)
scores = {task_id: cos(ngrams(l), ngrams(seed[task_id]))}
task_id = argmax(scores)
if max(scores) < θ_low:
    return VLA_ONLY
contract = contracts[task_id]
attrs = rule_extract(l)   # colors, order, count, tool
merge(contract, attrs)
```

**回退**：

- 匹配置信度低 → 不套契约，VLA 开环；
- 契约阶段卡住 → 允许 VLA 重规划；
- 契约与地图冲突（目标丢失/被移动）→ 触发 RECOVER，而不是硬执行。

### 4.4 离线实验结果（B）

**实验 E1：同义指令任务识别**

- 训练：每个任务只用第 1 条指令（32 条）；
- 测试：其余 4 条同义指令（128 条）；
- 方法：字符 3-gram 余弦最近邻；无学习权重。

| 方法 | 正确/总数 | 准确率 |
|---|---:|---:|
| 字符 3-gram 最近邻 | 119/128 | **93.0%** |
| 词集合 Jaccard 最近邻 | 118/128 | 92.2% |

错误主要集中在语义相邻任务：

- `DisconnectEthernet` → `PlugInEthernet`（“pull out” vs “insert”）；
- `PackBag` → `OrganizePencilCase`（“pencil box inside backpack” vs “stationery inside pencil case”）；
- `ZipUp` / `StorePaddle` → `OrganizePencilCase`（都含 zipper）；
- `OrganizeStationery` → `OrganizePencilCase`（stationery vs pencil case）；
- `PackPhone` → `StoreEarphones`（“inside box”）。

这些错误恰好是契约 schema 能区分的：动作极性（insert/remove）、对象角色（source/target/tool）、容器嵌套关系。加 5–10 条极性/角色规则即可把 93% 提到接近 100%；这也是 I1 的 G1 门。

**实验 E2：语言结构覆盖（B，关键词粗筛）**

| 结构 | 任务数/32 | 示例 |
|---|---:|---|
| 多子句（逗号/and/then） | 17 | OrganizePencilCase、PackBag、ToolboxStorage |
| 显式顺序/序列词 | 7 | ArrangePlates、ColorArrangement、StackBowls、StoreCups |
| 颜色相关（颜色词或 matching color） | 5 | ArrangePlates、StackBowls、ColorArrangement、FruitSorting、PickOutBatteries |
| 数量/全称量词 | 8 | FruitCollection、PaperCupStacking、ToolboxStorage、PackDoll |
| 具体空间/容器关系 | 26 | HangCup、PackDoll、StoreEarphones、OrganizeBookshelf |

结论：语言契约不是“为了优雅”，而是覆盖了相当一部分任务的真实结构。

## 5. TO-SLAM：桌面对象级因子图

### 5.1 为什么不是完整 SLAM

| 完整 SLAM | TO-SLAM |
|---|---|
| 建整张地图、回环、稠密重建 | 只建任务相关对象锚点 |
| 可能需要 RGB-D/LiDAR | 只有四路 RGB + 头双目 |
| 导航/定位为主 | 桌面操作/伺服为主 |
| 计算重 | 30 帧滑动窗口，CPU 5–10 Hz（目标） |
| 长期地图 | 单 episode 内持久；不跨 episode |

### 5.2 相机位姿

- 离线：按字段名，`state_d435` 给头相机（D435）在 base 系的 6D 位姿；需用 URDF/标定复核。
- 在线：API 给 `lower_body [15]`，其中 `[-3:]` 是腰 yaw/roll/pitch；用 G1 URDF 正运动学计算 `T_base_head`；再用一次标定得到 `T_head_cam`。
- 每台机器人一次重投影校准；误差 >5px 则只用头双目 PBVS，腕部用其 color 内参做 2D/IBVS 粗对齐。

### 5.3 对象表示与数据关联

对象锚点：

```text
O_i = {
  id, label, role,            # 契约里的 source/target/tool/distractor
  pose T_base_obj,            # 6D
  covariance,                 # 6x6
  extent,                     # 尺寸/点云包围盒
  status,                     # visible/occluded/moved/lost
  last_seen, confidence
}
```

数据关联打分：

```text
score(i, detection) =
    w1 * language_match(label, contract)
  + w2 * geometric_gate(T_base_obj, detection)
  + w3 * appearance(ORB/color histogram)
  + w4 * temporal_consistency
```

- 语言锚点优先：契约当前阶段只关心 `o_t`，其他对象降权；
- 几何门控：马氏距离 `(z - H O_i)^T S^{-1} (z - H O_i)`；
- 外观：颜色直方图/ORB；不用第二个学习模型；
- 时序：上一帧位姿预测。

### 5.4 扰动检测与恢复

```text
if external_i(t):
    mark O_i status=moved
    if O_i is current target:
        hold position
        re-localize O_i with head stereo
        if visible: update anchor; resume servo with conservative gain
        else: request VLA re-plan with new image + language
    else:
        keep O_i in map but downweight
```

人为干扰轴占 20%；这是性价比最高的单项。恢复不需要“识别人类”，只需要“场景动了，而且不是我的动作解释的”。

### 5.5 透明/反光/变形

- 透明/反光（杯子、试管、药瓶）：双目视差可能失败；用腕部目标图 + 已知几何尺寸 + 轮廓/边缘；置信度低 → 不启用 IBVS，只做 PBVS 粗对齐。
- 变形（毛巾、袋子）：不建刚体位姿；只跟踪包围区域/关键点；VLA 主导，地图只提供“大致区域”。
- 目标被夹爪挡住：用演示的 EE 位姿反推，或只存腕部目标图；地图标记 `occluded`，不要当成 `lost`。

## 6. J-SERVO：关节空间执行

### 6.1 从 WLA EE 规划到关节目标

```text
WLA 输出 30 步相对 EE（当前 EE 系，xyz+rotvec）
  ↓ compose 到 plan-time 当前 EE
T_base_ee_abs[k] = T_base_ee_current @ exp(a_rel[k])
  ↓ 取 5 步切片
T_base_ee^d[0..4]
  ↓ IK + 零空间
q_cmd[0..4] ∈ R^7
  ↓ 关节限幅/平滑
action.left_arm/right_arm
```

### 6.2 IK 与零空间

- 阻尼最小二乘：`Δq = J^T (JJ^T + λ^2 I)^{-1} e`；`λ` 随奇异值自适应。
- 零空间：`N = I - J^+J`；`q_cmd = q* + N(q_N - q*)`。
- `q_N` 目标：
  - 可操作度 `sqrt(det(JJ^T))` 最大；
  - 关节限位裕度最大；
  - 与演示姿态 `q_demo` 最接近（按阶段取演示中位数）。
- 关节顺序：`shoulder_pitch, shoulder_roll, shoulder_yaw, elbow, wrist_yaw, wrist_roll, wrist_pitch`。
- 限幅：`|q_{t+1}-q_t| ≤ Δq_max`；`|Δ²q| ≤ a_max Δt²`；`|Δ³q| ≤ j_max Δt³`。
- 失败回退：IK 无解/接近奇异/关节限位 → 回退 EE 模式或 VLA 开环。

### 6.3 关节跟踪误差接触代理（J-PC）

- 输入：`q_cmd`（我们返回的关节目标）、`q_meas`（下一帧 `observation.state.left_arm/right_arm`）。
- 信号：`c_t = ||q_cmd - q_meas||_2`；按关节分组（左/右臂）。
- 判定：`c_t > μ_c + 3σ_c` 且 `(q_cmd - q_meas)^T v_cmd > 0`。
- 用法：
  - 接触段降低法向增益、保留切向；
  - `c_t` 突降 + 物体随夹爪运动 → 滑移/掉抓；
  - 连续 3 块 `c_t` 高 → 回撤/重抓/重规划。
- 局限：不是力估计；依赖 evaluator 的低层 PD 增益/前馈；如果控制器很硬，信号可能很小。必须先离线验证 AUROC。

**离线 pilot（C）**：HangCup episode 0 前 200 帧，`action.left_arm[t]` 与 `state.left_arm[t+1]` 的关节误差均值 **0.051 rad**，最大 **0.127 rad**；说明信号非零且可阈值化，但尚未对齐接触标签，不能声称与接触相关。G4 要用 GEO-RESIDUAL 的接触标签做 AUROC。

### 6.4 平滑与 pivot 冻结

- 对 5 步关节目标做三次多项式/DCT 平滑；限制速度/加速度/jerk。
- `pivot`：抽样 HangCup 前 100 帧，`action.pivot` 恒为 `[0,0,0,0,0.15,0,0.74]`；演示中下身体/腿变化很小，但需统计 32 任务整段 episode 后才能冻结。建议：
  - 先统计 32 任务的 pivot 分布；
  - 若某任务 pivot 恒定，直接输出该常数，不交给模型预测；
  - 若某任务 pivot 变化，回退模型预测/演示中位数。
- 这样把 21 维动作（joint 模式）压到 16 维（2×7 关节 + 2 夹爪），减少无关维度噪声。

## 7. 集成：JOLT 的一次 `get_action`

```text
输入：obs（四路 RGB、关节、EE、夹爪、lower_body、language）、token
1. 契约：match(language) → task_id/contract；若置信度低 → VLA_ONLY
2. 地图：TO-SLAM.update(obs) → M_t；若当前目标丢失 → RECOVER
3. 规划：VLA 异步产 30 步 EE plan；plan 过期用旧 plan
4. 目标：contract.current_target(M_t) → T_base_target
5. 执行：J-SERVO.solve(ee_plan[0:5], q, T_base_target) → q_cmd[0:5]
6. 接触：J-PC.detect(q_cmd, q_meas) → 调整增益/回撤
7. 验证：contract.check(M_t)；若阶段完成 → NEXT；若违反 → RECOVER
8. 返回：joint 动作 + gripper + pivot 常数 + meta.token
```

**安全**：

- 任何异常 → 返回上一组合法 chunk 或安全 hold；
- 限速/限幅/最大重试；
- 人为干扰/目标丢失 → 先停，不硬追；
- 关节模式失败 → 回退 EE 模式；
- 端口隔离：每个端口独立契约/地图/伺服，`reset()` 清空。

### 9.1 任务组合（先验，待单任务通道更新）

| 组合 | 任务 | 主投层 | 理由 |
|---|---|---|---|
| **A：LANG+MAP+JOINT** | OrganizePencilCase、PackBag、ToolboxStorage、StoreEarphones、ArrangePlates、ColorArrangement、StackBowls、PaperCupStacking、PickOutBatteries、SyringeWaterTransfer、Unlock、PlugCharger、PlugInEthernet、HangCup、ZipUp | 三层都用 | 顺序/颜色/计数/多阶段/工具/接触 |
| **B：MAP+JOINT** | FruitSorting、OrganizeBookshelf、PlacePhotoFrame、OrganizeTools、OrganizeStationery、StoreCups、StorePaddle、PackPhone、PourOutMedicine、RemovePinnedNote、ArrangeTestTubes、DisconnectEthernet | 地图+伺服 | 目标位置/遮挡/接触，语言结构较简单 |
| **C：VLA 优先** | FoldTowel、ConveyorSorting、SpellRobot、PackDoll、FruitCollection | VLA | 变形/动态/语义/长程，几何伺服收益低 |

组合规则：

```text
priority_t = q_t * Δ_t / cost_t
```

- `q_t`：失败发生在“结构/最后 3 厘米”的比例（先用语义先验，单任务通道后更新）；
- `Δ_t`：JOLT 条件增益（A/B 差值）；
- `cost_t`：工程/评测成本（契约/地图/标定/调参）。

先做 A 档中 `q_t` 最高、`cost_t` 最低的 3–5 个任务；不要一次铺 15 个。

### 9.2 单任务通道协议

| 项 | 设计 |
|---|---|
| 任务 | ArrangePlates、OrganizePencilCase、PickOutBatteries、PlugInEthernet、FoldTowel |
| 次数 | 每任务 5–8 次 A/B |
| 初始条件 | 同一位置/背景；尽量配对 |
| 指标 | 成功率、步骤分、耗时、p99、恢复次数、契约违反次数 |
| chunk | 先固定 5；通过后扫 3/8 |
| 通过 | ≥3/5 任务 +10pp；FoldTowel 不回归 >5pp |
| 失败 | 不提交 JOLT 版本；只保留离线分析 |

统计：

- 配对差值 `Δ_t = p_on - p_off`；5–8 次/任务只能看方向，不能看显著性；
- 汇总 5 任务用 bootstrap；报告 95% CI；
- 若 CI 跨 0，继续测或放弃；不要用 +1–2pp 做结论。

### 9.3 收益算术

- A 档 15 任务各 +10pp → `15/32×10 = +4.7pp`；
- 若只有 10 个任务生效 → `+3.1pp`；
- human 轴 +10pp → `+2pp`（20% 权重）；
- 保守合计 **+4–7pp**；乐观 +8–10pp；
- 若 LANG/MAP/JOINT 只有部分生效，按实际 A/B 折算；
- 这些是设计目标，不是承诺；G5/G7 不过就不提交。

### 9.4 提交节奏

1. **W0**：WLA + API adapter + 安全基线；单任务通道跑通 1 个任务（token/pivot/joint 顺序）。
2. **W1**：若允许多次提交，先交安全基线锁 tie-break；若只允许一次，跳过。
3. **W2–W3**：LANG-CONTRACT 离线编译 + 160 条验证；单任务 A/B。
4. **W3–W5**：TO-SLAM + J-SERVO；5 任务 A/B。
5. **W5–W6**：全量干跑 32×10；N 端口隔离；p99/内存。
6. **W6**：最终提交；保留回退开关。

## 11. 风险与合规

### 11.1 单模型合规的三种模式

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 契约/地图只离线生成标签；线上只有 VLA | 最低 | 保守首选 |
| C2 确定性控制器 | 契约=静态配置+规则；地图=几何估计；伺服=控制律；VLA 唯一学习模型 | 低；需向官方说明 | 主推 |
| C3 同 checkpoint 特征 | 需要语义特征时用 VLA 同一 checkpoint 的 encoder | 低–中；需说明 | 需要强描述子时用 |

禁止：加载第二个学习策略/残差网络/独立视觉编码器（SAM/CLIP 等）做在线决策。离线 LLM 只用于开发期生成契约，不进入推理路径。

### 11.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 契约解析错 | 错误子目标 | 置信度门控；低置信回退 VLA；160 条验证 |
| 同义指令未见 | 任务 ID 错 | 5 条同义训练/验证；字符 n-gram + 极性规则；回退 |
| 地图漂移/遮挡 | 目标位姿错 | 协方差门控；重定位；透明/变形回退 |
| 人为干扰误判 | 频繁停机 | 鲁棒核；EE 距离/夹爪状态联合判断；最大重试 |
| 关节模式不稳定 | 抖动/限位/奇异 | 阻尼 IK；零空间；限幅；回退 EE |
| evaluator 控制器不匹配 | 跟踪误差无意义 | G0 先验证；J-PC 只做辅助；视觉接触相位兜底 |
| 真机腕部内参与数据不一致 | 2D 伺服不准 | 重投影校验；头双目 PBVS 兜底 |
| `pivot` 语义不一致 | 下身体乱动/不动 | 先返回常数 pivot；单任务通道验证；回退零 pivot |
| 单模型解释 | 被判定为第二个模型 | C1/C2/C3；提交材料写清楚；无学习权重 |
| 远程 RTT 高 | 反馈周期长 | 5 步 chunk；RTT 测量；预测补偿；回退 8–10 步 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；SE≈2.4pp |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景划分；同义句不跨 split |
| 跨 episode 记忆 | 违反独立性 | 不做；每 episode 清空地图/契约状态 |
| 提交次数限制 | 无法多次 A/B | 邮件确认；单任务通道先验证；一次提交则保守 |
