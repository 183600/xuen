# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配×主动交互的不确定性二分」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「安全对齐」×「开源软件」）

> R69 把不确定性拆成 aleatoric/epistemic，用主动交互去消解，并交付了一张 J_FLUID 证书。但它整条保证链是**闭世界**的：证书由系统自己签发（自证），「k 个正交证据源一致」默认攻击者不知道会查哪几个源（隐晦式安全），模态校准门默认数据与参考分布可信（供应链盲区），安全被当成一次性的「验讫」而非需要持续维护的过程。R69 自陈的最大风险已经贴到这个洞上：一旦模态分布不可信，交互会把「诚实的不知道」升级成「被证实的错误」。
>
> 本轮两个灵感各自补一半：
> - **开源软件**真正厉害的不是「代码免费」，而是一套**让互不信任的陌生人也能验证、组合、复现、打补丁**的机制：可复现构建、来源签名、依赖与版本、评审合并、漏洞披露，以及 Kerckhoffs 原则（安全不能靠藏）。
> - **安全对齐**不是一次性训练属性，而是**「声明意图」与「实际行为」之间被持续维护的契约**；最难的从来不是通过测试，而是测试/证书本身被 Goodhart 化——优化了可测代理，丢掉了真实目标。
>
> 核心命题：**把 R69 的「自签证书」升级为「开源可验证的安全对齐供应链」。** 每一条安全声明都必须（i）在机器可检清单里显式声明；（ii）可与其依赖组合并证明不弱化安全包络；（iii）能被任意第三方从固定产物复现；（iv）在机制完全公开（Kerckhoffs）的对抗模型下仍成立；（v）经漏洞披露—补丁—撤销的生命周期维护；（vi）在异构分叉之间协商出共同安全包络。并且必须显式区分「合规（行为符合声明）」与「适切（声明本身对齐）」——**前者可开源验证，后者不可由系统自证**。
>
> 命名 **FORGE-RAS**（Forkable, Open, Reproducible, Governed, Evidence-based Risk-adaptive System；开放可复现、可组合、可打补丁的安全对齐闭环）。「forge」一语双关：既是开源 forge（代码锻造场），也是对抗者的伪造，还是签名的铸造。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**凭什么相信这份证明本身——它可被任何人复现、组合、攻击和打补丁吗**」。安全不是一个封条，而是一份任何人都能审计、且必须持续维护的公共契约。

## 0. 直觉与动机

**灵感 1（开源软件 → 安全是一条可复现的供应链，而不是一张自签收据）**
直觉：开源生态真正厉害的不是「免费」，而是**让互不信任的陌生人对同一份产物达成一致**：内容寻址让「偷换权重」无所遁形；可复现构建让「我这儿能跑」变成「谁都能复跑」；依赖清单把隐式假设变成显式引用；签名与评审让每次改动留下可追责痕迹；漏洞披露把「不知道的坏」变成「已知并正在修」。R69 的 J_FLUID 恰是反面：由被审系统自己产出、由同一套代码解释、外部无法重放——这是**证词**，不是**证据**。开源第一课：证据必须能被与你利益相反的第三方独立重算。

**灵感 2（安全对齐 → 合规 ≠ 适切；证书会被 Goodhart）**
直觉：对齐的核心裂缝是「规格—行为」二义：行为符合规格，只说明系统忠实执行了写下的东西；若写下的东西漏了、错了、或可被钻空子，合规反而是**更危险的自信**。而一旦测试集/证书成为公开目标，优化压力会把它压成一个可刷的分数。所以「安全对齐」在开放世界里必须包含三件事：可组合的规格（不是一句口号）、对规格本身的对抗性外审（红队/复现挑战）、以及防刷分的**密封轮换评测**。

**灵感 3（两者相乘 → R69 的隐晦式安全在开源下失效）**
直觉：R69 的「k 个正交源一致」默认攻击者不知道会查哪几个源、哪个模态对。代码一开源，攻击者能精确地只污染会被查询的那几个「正交」源，甚至让多个源共享同一个被投毒的上游（伪正交）。于是「正交」从**设计假设**变成需要**运行时审计并证明**的量。解决不是把机制藏回去（既违背开源又可被逆向），而是用**承诺—揭示**把「选哪个证据」变成攻击者在作答时无法预知的随机挑战，并用公开随机信标/VDF 时间锁绑定，防止系统自己挑对自己有利的挑战。

**灵感 4（开源的分叉 → 安全包络的语义版本与共识）**
直觉：开源意味着分叉。机队里不同机器人可能跑不同 fork 的感知/策略/问句解码器。R69 讨论单机单版本；真实部署里「我的安全」与「邻居的安全」可能不是同一个版本。需要像语义化版本那样声明「我的安全包络相对基线变了什么」，并在异构节点间取**安全包络的交集**；交集为空就安全拒绝任务，而不是偷偷取并集。

**灵感 5（把最后一道防线放到不可被 fork 掉的地方）**
直觉：开源也意味着任何人都能删掉安全过滤器、微调掉拒绝行为。所以**不能把最后防线放在可被修改的大模型里**。必须有一个极小、形式化验证、公开可审计的 **root-of-trust kernel（RTK）** 硬性执行安全包络；庞大的流策略/LLM 解码器全部标记为不可信外圈，只能提议、不能越界。这是开源安全的结构性回答：信任锚要小到能被彻底读懂。

**灵感 6（对 R69 的正面对偶：从「第二意见」到「第二实现」）**
直觉：R69 用流似然给标定一条独立第二意见。开源给出更强对偶：**第二实现**——同一份规格由独立团队从零实现，两者在同一输入上行为一致才提高置信；不一致时暴露的往往是规格歧义而非单纯 bug。这把冗余从数据层提升到**实现层**，正好补 R69「单实现自证」的根缺陷。

## 1. 形式化定义（增量：定义 310–327）

**定义 310（FORGE-RAS 总览）** FORGE-RAS = (ALM, SCC, RRV, KAM†, CRD, IAU, SVL, FSV, RTK, GCR, FCA, J_FORGE)。四不变式：
(i) **失败关闭**：任一供应链检查（清单/组合/复现/独立性/撤销）不通过，安全包络收缩而非放行；
(ii) **合规—适切分离**：J_FORGE 只声明并证明合规；适切只能由外部对抗性评审与密封轮换评测提供，绝不写成系统自证；
(iii) **信任锚最小化**：所有安全硬约束最终由 RTK 执行，外圈学习组件不可绕过；
(iv) **可撤销**：任何已签发证书可被安全漏洞流程撤销，撤销在机队内单调传播。

**定义 311（对齐清单 ALM）** 每个组件 c 附带清单 `M_c = (id, ver, intent, O_c, A_c, G_c, E_c, F_c, T_c, deps, provenance, license)`：义务 O、假设 A、保证 G、证据指针 E、已知失效 F、威胁模型 T。O/A/G 用可检逻辑片段表达，E 为内容寻址指针。`H(M_c)` 进入证书；**未在清单中声明的行为视为越界**。

**定义 312（保证代数与安全组合 SCC）** 保证 G 是安全包络上的单调算子（如「在假设 A 下动作集 ⊆ S」）。组合：`A_∘ = (∪A_i) \ (∪被 discharged 的依赖 G_j)`；若 SCC 能证明每条跨组件假设被某个依赖保证蕴含，则 `G_∘ = ⋂_i G_i`（保守取交），否则 `G_∘ = G_⊥`（空包络，失败关闭）。定义**传递信任缺口** `Γ = G_claimed − G_∘`，仅当 `Γ=∅` 允许合并。

**定义 313（可复现证书与重放关系）** RRV 证书携带 `R = (image_digest, data_digest, seeds, hw_profile, expected_output_digest)`。验证者独立重放得 `digest'`，`Reproduce(J) ⇔ digest' = expected`。替换权重/数据/评测代码导致失配的概率由抗碰撞性界定。**Reproduce 只证明「跑的是所声明的程序」，不证明「程序目标正确」。**

**定义 314（Kerckhoffs 对抗模型 KAM†）** 攻击者 A 已知全部代码、权重、清单、测试、组合规则与随机化算法，仅受算力预算 `B_c` 与投毒预算 `B_p` 约束。安全声明须在 `min_{A∈KAM†}` 意义下成立；任何依赖「攻击者不知道 X」的论证一律降级为**未证明**。

**定义 315（披露鲁棒性）** 若把机制 X 从公开改为隐藏会使某声明由成立变不成立，称该声明**披露脆弱**。FORGE 要求所有安全声明披露鲁棒；披露脆弱者只能作为效率优化，不得进入安全包络证明。

**定义 316（承诺—揭示证据协议 CRD）** 系统收集交互证据前先发布 `h=H(seed)`（用公开随机信标或 VDF 时间锁绑定，防事后挑选），人在不知 seed 时作答，随后揭示 seed，由 seed 导出「查哪一对证据 / 用哪种探针扰动」。攻击者必须在不知挑战时预先污染，协调投毒优势被压到挑战族最小熵。**证明不了 seed 未被事后选择 ⇒ 本次证据不计入定案。**

**定义 317（独立性审计 IAU）** 证据源独立性不假设而估计：`ρ̂_ij` 由共享来源图（同一上游模型/传感器/数据/镜像）与行为残差相关共同估计；有效独立源数 `k_eff = (Σλ)²/Σλ²`（参与比）。若 `k_eff < k_req(τ)`，则「k 正交一致」降级为未达标，U_epi 不消解并走 R69 兜底。**伪正交/单一栽培在此被显式惩罚。**

**定义 318（安全漏洞生命周期 SVL）** 每个声明维护状态机：`unknown → discovered → triaged → disclosed(协调窗口) → patched → regression_added → rolled_out(canary→fleet) → revoked/closed`；每次转换有签名与时限。证书引用其依赖声明的 SVL 状态，存在 open/triaged 高危项即自动降级。

**定义 319（分叉血缘与安全语义版本 FSV）** fork f 声明 `base_version b_f` 与 `diff Δ_f`。合并门检查：`Δ_f` 不得削弱任何被依赖 G（**safety-monotone**）；新增依赖需可复现清单与来源签名（防依赖混淆/抢注）；记录血缘 DAG。定义 **safety-left**：分叉必须保留并可复跑父版本全部回归测试，否则不得宣称继承其安全等级。

**定义 320（信任根内核 RTK 与不可信外圈）** RTK 是极小状态机，公开形式化规格与机器可检证明，硬执行：安全包络 S(x)、动作裁剪、看门狗、撤销查询。外圈（FMP、LLM 解码器、交互规划器）只可向 RTK 提议 ξ；RTK 不读外圈可学习参数。RTK 是唯一 TCB，其代码量与证明义务受硬上限约束。

**定义 321（Goodhart 抗性评测 GCR）** 评测 = 公开回归套件 `Pub` ∪ 密封轮换套件 `Seal`。Seal 由承诺—揭示抽取并定期更换；证书需两者同时达标。泛化缺口 `γ = perf(Pub) − perf(Seal)`；`γ>τ_g` 判为对公开测试过拟合，证书降级。Seal 由多方可复现构造，避免评测方垄断。

**定义 322（双实现交叉验证）** 同一规格 R 的两个独立实现 `impl_A, impl_B` 在输入分布上一致率 `≥τ_bi` 时，才把「规格—实现一致」计入证据；不一致样本进入**规格歧义池**，由外部评审消解，而不是任选一个实现当真相。

**定义 323（多分叉安全包络共识 FCA）** 节点各有证书包络 `S_i(x)`。执行前求 `S_∩ = ⋂_i S_i`；若 `S_∩=∅` 或某节点证书被撤销 ⇒ 安全拒绝/降级，禁止取并集。共识只针对硬安全约束；效率策略可各自不同。

**定义 324（J_FORGE 证书）** `J_FORGE = (J_FLUID, {H(M_c)}, π_SCC, replay_digest, k_eff, disclosure_robust_flags, SVL_state, revocation_set, γ_goodhart, bi_impl_agreement, fork_lineage_hash, forge_ver)`。Valid ⇔ J_FLUID 有效 ∧ 组合证明通过 ∧ Reproduce 成功 ∧ `k_eff≥k_req` ∧ 无披露脆弱安全声明 ∧ 撤销集不命中 ∧ `γ≤τ_g`。**Valid 只表示合规，不表示适切。**

**定义 325（退化到 R69）** 当清单图退化为单节点、无分叉、无外部贡献、`Seal=∅` 且 RRV 恰好复现 J_FLUID 时，FORGE 在线闭环与 R69 逐指令相同，附加字段为中性常量。R69 = FORGE 在「闭源单实现、无可复现」边界上的退化。

**定义 326（撤销单调性与对齐债）** 撤销集 `R_t` 单调增长（除非通过同等证明重新认证）；已执行动作不可撤销，故撤销只影响未来。定义**对齐债** `D_align = Σ_c w_c·unresolved(open vulns)_c`；`D_align` 超阈 ⇒ 机队进入保守模式（等价 R69 最保守）。

**定义 327（传递信任风险的界）** 依赖图有 n 个组件、每个组件声明被高估 `ε_i`，则组合后未检出风险期望 `≤ Σ_i ε_i + Σ_edges Γ_e`；SCC 的作用是显式给出每个 `Γ_e` 的上界。无 SCC 时 Γ 无界（见引理 19 反例）。

# IP-264 ALM：对齐清单与清单门（离线，被 J_FORGE 引用）
def admit_component(M_c, deps):
    assert schema_ok(M_c) and M_c.intent.consistent(M_c.obligations)
    for d in deps:                                  # 依赖来源/签名/血缘
        assert verify_provenance(d) and H(d.manifest) in M_c.deps
        assert not typosquat(d.id, trusted_registry)
    assert M_c.threat_model.covers(KAM_OPEN)        # 必须覆盖机制全公开
    return M_c.id

# IP-265 SCC：rely-guarantee 组合；不 discharge 就失败关闭
def compose(graph):
    G = {}                                          # component -> guarantee
    for c in topo_order(graph):
        A_undischarged = c.A - union(G[d] for d in c.deps)
        if A_undischarged:                          # 依赖没有兑现其假设
            return G_bottom                          # 失败关闭，非放行
        G[c] = c.G
    G_composed = intersect(G.values())              # 保守取交
    assert (graph.claim - G_composed) == EMPTY       # 传递信任缺口必须为零
    return G_composed

# IP-266 RRV：第三方可从固定产物复现（证明是证据，不是证词）
def verify_certificate(J, recipe):
    digest = hermetic_replay(recipe.image, recipe.data,
                             recipe.seeds, recipe.hw)  # 内容寻址 + 固定种子
    if digest != recipe.expected:
        return Verdict.REPLAY_MISMATCH              # 一票否决
    return Verdict(replay_ok=True, adequacy="UNPROVEN")  # 合规已证，适切未证

# IP-268 CRD：承诺—揭示，防协调投毒 + 防系统事后挑挑战
def crd_collect(challenge_family, human, beacon, vdf):
    seed   = beacon.future_seed(vdf)                # 作答时不可知，事后可验
    commit = H(seed)
    publish(commit)
    answer = human.respond_without(seed)            # 人在不知挑战下作答
    reveal(seed); assert H(seed) == commit and vdf.verify(seed)
    pair   = derive_pair(seed, challenge_family)    # 查哪一对证据
    return answer, pair, "seed_bound"

# IP-269 IAU：独立性不假设而测；伪正交即降级
def independence_audit(sources, residuals):
    k_eff = participation_ratio(source_weights(sources))
    for i, j in pairs(sources):
        rho = correlation_from(provenance_graph(i, j), residuals[i], residuals[j])
        if rho > RHO_MAX: k_eff -= penalty(rho)   # 共模/单一栽培惩罚
    return k_eff

# IP-272 RTK：唯一 TCB，硬执行包络（外圈一切可 fork，唯独这里不行）
def rtk_gate(xi, S, revocation):
    if revocation.hit(xi.component_ids): return DENY
    if not inside_envelope(xi, S):       return CLIP(xi, S) or DENY
    return ALLOW                                    # 形式化验证的小内核

# IP-273/322/323/324/276：评测、双实现、分叉共识与主闭环
def forge_round(M, obs, fleet):
    z, o = M.mtm.forward(obs); c, U_cal, _ = M.cof.step(o)     # R69 计量层
    # 1) R69 在线消歧（K/交互/VoI），证据纪律升级为 CRD + IAU
    K = 1 if M.fmp.mode_head(z) < TAU_MODE else 4
    U_ale, U_epi, modes = M.aud.decompose(M.fmp.sample(o, K), z)
    answer, pair, bind = M.crd.collect(M.challenges(modes), M.human, M.beacon, M.vdf)
    k_eff = M.iau.audit(M.sources(modes), M.residuals)
    if k_eff < M.k_req: U_epi = max(U_epi, TAU_EPI)            # 未达标 → 不消解
    # 2) 组合证明 + 撤销检查（失败关闭）
    S = M.scc.compose(M.graph) if M.scc.valid(M.graph) else G_bottom
    if M.revocation.nonempty() or M.align_debt > TAU_DEBT: S = G_bottom
    # 3) R69 风险缩放；未消解 epistemic 与 R68/R69 兜底一致
    U_floor = U_ale + (U_epi if answer is None else 0.0)
    lam = max(M.efs.risk_scale(o), lam_floor(U_floor))
    xi  = M.flow.propose(o, modes, lam, with_info=True)
    # 4) 多分叉共识取交；空则安全拒绝（禁止并集）
    S_fleet = fleet.consensus_envelopes(S)          # ⋂ S_i
    if S_fleet.empty: return SAFE_REFUSE
    # 5) 最后防线：RTK 硬执行，外圈不可绕过
    xi  = M.rtk.gate(xi, S_fleet, M.revocation)
    # 6) 离线：密封评测/双实现/生命周期；异步签发 J_FORGE（仅声明合规）
    M.vqa_i.submit_async(answer, pair, bind, k_eff)
    J = J_FORGE(J_FLUID=M.certify(o), replay=M.rrv.recipe(),
                goodhart=M.gcr.gap(), adequacy="EXTERNAL_REVIEW_ONLY")
    return xi, J
```

## 3. 推导

**引理 19（组合可靠性与传递信任的反例）** 设每个组件 i 在其假设 `A_i` 下满足 `G_i`。若 SCC 证明了每条跨组件假设被依赖保证蕴含，则组合在 `A_∘` 下满足 `⋂G_i`（rely-guarantee 归纳，单调取交只会更保守）。反之，若不做 SCC，可构造两个各自「安全」的组件：A 假设「B 已限速」，B 假设「A 已限幅」，组合后既无限速又无限幅，真实风险任意大且各自清单都显示绿色——**这就是传递信任缺口 Γ 无界**。系：安全不能只逐组件打勾，必须证明假设的 discharge。

**引理 20（复现的可替换检测性）** 证书含内容寻址的 `image/data/seeds` 与期望输出摘要。若攻击者替换任一被评测产物且不改变摘要，则需破坏底层哈希的抗碰撞性；若改变摘要，则与签发证书不一致而被拒。故在抗碰撞假设下，任何未被检测的替换概率可忽略。**但**该引理只覆盖「跑的是什么」，不覆盖「目标对不对」——把二者混淆正是自证证书最常见的谬误。

**引理 21（承诺—揭示对自适应投毒的抑制）** 设挑战族 `𝒞` 的最小熵为 `H_min`，攻击者在作答前不知挑战、只能对全部源投放总预算 `B_p`。采用 CRD 后，其命中「将被查询源」的协调优势以 `2^{−H_min}` 指数衰减；相比无 CRD 的「精确污染被查询源」，期望错误采纳率下降因子 `≤ 2^{−H_min}`。若系统可事后挑 seed，则优势消失，故必须用公开信标/VDF 绑定。系：**R69 的 k-正交纪律在开源下的有效性，取决于 CRD 的绑定质量，而不取决于宣称的 k。**

**引理 22（有效独立源与共模惩罚）** 若真实源相关矩阵为 `R`，参与比 `k_eff` 满足 `k_eff ≤ k`，且 `k_eff = k` 当且仅当源两两独立。多数表决错误率随 `k_eff` 而非名义 k 指数下降；共享上游的伪正交使 `k_eff` 骤降。故 IAU 估计的 `k_eff` 是证据纪律可信度的**可观测充分统计量**（在二阶相关近似下）。

**定理 18（FORGE 严格包含 R69 且安全侧失败关闭）** 在 A99–A101 下，若所有供应链检查通过，则 FORGE 的在线安全包络 `S_FORGE ⊆ S_R69` 且风险缩放不低于 R69 的 λ_floor；当退化条件（定义 325）成立时两者逐指令相同。任一检查失败则 `S_FORGE = G_⊥ ⊆ S_R69`。故 FORGE 不会比 R69 更不安全；它用「可复现/可组合/可撤销」换取效率和可审计性，而把不确定性一律推向失败关闭。

**定理 19（披露鲁棒性的必要性）** 在 KAM†（机制全公开）下，任何披露脆弱的「k 正交一致」声明都存在一个多项式时间攻击者，使其错误采纳率不随 k 增长（因为它能精确污染被查询源并伪造伪正交）。CRD + IAU 把该攻击的错误率压回 `O(2^{−H_min})+ε_σ`。系：**开源不是安全的敌人；靠隐藏换来的安全才是。**

**定理 20（分叉共识的安全性）** 若每个节点的证书包络 `S_i` 对其自身组件是可靠的，且 RTK 只执行 `S_∩=⋂S_i`，则机队执行的每个动作对所有参与节点均安全；当 `S_∩=∅` 时拒绝任务（失败关闭），不会出现「取并集导致的静默不安全」。若允许某节点离线且其证书未撤销，则其安全义务仍被并集外扩——故 FCA 必须使用**在线成员的最新证书**，而非缓存版本。

**命题 1（合规可证、适切不可自证）** 对任意内部可计算的证书系统 C，存在两个世界 W1、W2 在 C 的全部可观测证据上不可区分，但其「声明是否符合人类意图」不同。因此不存在仅由系统内部证据签发的证书能推出适切性；适切只能来自外部、对抗性、多元的评审与真实后果反馈。这不是工程缺口，而是「规格—行为」问题的信息论边界。**FORGE 把这条边界写进 J_FORGE 的 `adequacy="EXTERNAL_REVIEW_ONLY"`，拒绝用合规冒充对齐。**

## 6. 本轮最大风险

**一句话**：FORGE 把安全从「黑箱信任」换成「公开可复现」，但**可复现只能证明「行为符合一份声明」，证明不了「这份声明真的对齐了人类价值」**——更危险的是，开源会让所有部署收敛到同一份被广泛验证的栈，一旦某个未被测试覆盖的对齐缺口存在，它会沿供应链同构放大（单点共性故障 + 价值锁定）：**我们能开源地证明我们遵守了规则，却无法开源地证明规则是对的。**

**次级风险与缓解**：
1. **公共测试被 Goodhart 刷分** → GCR 密封轮换套件 + 泛化缺口门 + 多方可复现构造；
2. **承诺—揭示被系统自身操纵 seed** → 公开随机信标/VDF 时间锁绑定，未绑定则证据不计入定案；
3. **RTK 自身有洞（信任锚失效）** → 极小 TCB + 形式化验证 + 公开审计 + 红队赏金；承认它是单点，故必须最小；
4. **供应链投毒/依赖混淆/抢注** → 来源签名 + 内容寻址 + 血缘扫描 + safety-left；
5. **分叉碎片化导致无法共识** → 失败关闭 + 安全降级模式，绝不静默取并集；
6. **把合规误当适切** → J_FORGE 显式标注 `adequacy=EXTERNAL_REVIEW_ONLY`，外部对抗评审与真实后果反馈是唯一适切证据。

        rho = correlation_from(provenance_graph(i, j), residuals[i], residuals[j])
        if rho > RHO_MAX: k_eff -= penalty(rho)       # 共模/单一栽培惩罚
    return k_eff

# IP-272 RTK：唯一 TCB，硬执行包络（外圈可 fork，唯独这里不行）
def rtk_gate(xi, S, revocation):
    if revocation.hit(xi.component_ids): return DENY
    if not inside_envelope(xi, S):       return CLIP(xi, S) or DENY
    return ALLOW

# IP-276 主闭环（继承 R69；证据/组合/共识/硬门）
def FORGE_RAS_round(M, obs, fleet):
    z, o = M.mtm.forward(obs); c, U_cal, _ = M.cof.step(o)      # R69 计量层
    K = 1 if M.fmp.mode_head(z) < TAU_MODE else 4
    U_ale, U_epi, modes = M.aud.decompose(M.fmp.sample(o, K), z)
    answer, pair, bind = M.crd.collect(M.challenges(modes), M.human, M.beacon, M.vdf)
    k_eff = M.iau.audit(M.sources(modes), M.residuals)
    if k_eff < M.k_req: U_epi = max(U_epi, TAU_EPI)             # 未达标 → 不消解
    S = M.scc.compose(M.graph) if M.scc.valid(M.graph) else G_bottom
    if M.revocation.nonempty() or M.align_debt > TAU_DEBT: S = G_bottom
    U_floor = U_ale + (U_epi if answer is None else 0.0)
    lam = max(M.efs.risk_scale(o), lam_floor(U_floor))          # R69 两级退避
    xi  = M.flow.propose(o, modes, lam, with_info=True)
    S_fleet = fleet.consensus_envelopes(S)                      # ⋂ S_i
    if S_fleet.empty: return SAFE_REFUSE                        # 禁止并集
    xi  = M.rtk.gate(xi, S_fleet, M.revocation)                 # 最后防线
    M.vqa_i.submit_async(answer, pair, bind, k_eff)
    J = J_FORGE(J_FLUID=M.certify(o), replay=M.rrv.recipe(),
                goodhart=M.gcr.gap(), adequacy="EXTERNAL_REVIEW_ONLY")
    return xi, J
```

## 4. 推导

**引理 19（组合可靠性与传递信任反例）** 若每条跨组件假设都被依赖保证蕴含，则组合在 `A_∘` 下满足 `⋂G_i`（rely-guarantee 归纳，取交更保守）。反之：A 假设「B 已限速」、B 假设「A 已限幅」，两者清单各自绿色，组合既无限速又无限幅，真实风险任意大 ⇒ 不做 SCC 时传递信任缺口 Γ 无界。

**引理 20（复现的可替换检测性）** 证书含内容寻址的 image/data/seeds 与期望输出摘要；替换产物而不改摘要需破坏抗碰撞性，改摘要则与证书不一致被拒。故在抗碰撞假设下未检出的替换概率可忽略；但该引理**只覆盖「跑的是什么」，不覆盖「目标对不对」**。

**引理 21（承诺—揭示对自适应投毒的抑制）** 挑战族最小熵 `H_min`、攻击者作答前不知挑战且总投毒预算 `B_p`，则 CRD 后命中「将被查询源」的优势以 `2^{−H_min}` 衰减；相对无 CRD 的精确污染，期望错误采纳率下降因子 `≤2^{−H_min}`。若系统可事后挑 seed 则优势消失，故必须信标/VDF 绑定。系：R69 的 k-正交有效性取决于 CRD 绑定质量，而非名义 k。

**引理 22（有效独立源与共模惩罚）** 源相关矩阵 R 下 `k_eff≤k`，等号当且仅当两两独立；多数表决错误率随 `k_eff` 而非名义 k 指数下降。共享上游的伪正交使 `k_eff` 骤降，故 IAU 的 `k_eff` 是证据纪律可信度的可观测充分统计量（二阶相关近似）。

**定理 18（FORGE 严格包含 R69 且失败关闭）** 在 A99–A101 下，供应链检查全通过时 `S_FORGE ⊆ S_R69` 且 λ 不低于 R69 的 λ_floor；退化条件成立时逐指令相同；任一检查失败则 `S_FORGE=G_⊥⊆S_R69`。故 FORGE 不比 R69 更不安全，用可复现/可组合/可撤销换效率与可审计性，把不确定性一律推向失败关闭。

**定理 19（披露鲁棒性的必要性）** 在 KAM† 下，任何披露脆弱的「k 正交一致」都存在多项式时间攻击者使其错误采纳率不随 k 增长（精确污染被查询源 + 伪造伪正交）；CRD+IAU 将其压回 `O(2^{−H_min})+ε_σ`。系：开源不是安全的敌人，靠隐藏换来的安全才是。

**定理 20（分叉共识的安全性）** 若各节点包络 `S_i` 对自身组件可靠、RTK 只执行 `S_∩=⋂S_i`，则机队执行的动作对所有参与节点安全；`S_∩=∅` 时安全拒绝，不会出现取并集导致的静默不安全。离线节点须使用在线最新证书而非缓存，否则其义务被静默外扩。

**命题 1（合规可证、适切不可自证）** 存在两个世界 W1、W2 在证书系统 C 的全部内部可观测证据上不可区分，但「声明是否符合人类意图」不同。故无任何纯内部证据证书能推出适切性；适切只能来自外部、对抗、多元的评审与真实后果反馈。这不是工程缺口而是信息论边界——FORGE 把它写进 `adequacy="EXTERNAL_REVIEW_ONLY"`，拒绝用合规冒充对齐。

## 7. 本轮最大风险

**一句话**：FORGE 把安全从「黑箱信任」换成「公开可复现」，但**可复现只能证明「行为符合一份声明」，证明不了「这份声明真的对齐了人类价值」**——更危险的是，开源会让所有部署收敛到同一份被广泛验证的栈，一旦某个未被测试覆盖的对齐缺口存在，它会沿供应链同构放大（单点共性故障 + 价值锁定）：**我们能开源地证明我们遵守了规则，却无法开源地证明规则是对的。**

**次级风险与缓解**：公共测试被 Goodhart 刷分（GCR 密封轮换 + γ 门）；系统操纵 seed（公开信标/VDF 绑定，未绑定不计入定案）；RTK 自身有洞（极小 TCB + 形式化验证 + 公开赏金，承认其为单点故必须最小）；供应链投毒/依赖混淆（来源签名 + 内容寻址 + 血缘扫描 + safety-left）；分叉碎片化无法共识（失败关闭 + 降级模式）；把合规误当适切（J_FORGE 显式标注 `EXTERNAL_REVIEW_ONLY`，外部对抗评审与真实后果反馈为唯一适切证据）。
