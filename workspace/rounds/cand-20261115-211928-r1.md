# 第 10 轮（新灵感循环第 2 轮；本轮灵感：「用户需求分析」×「强化学习训练」）
> **基线**：第 9 轮 MetricVoiceGauge-ACMD（定义 532–539；引理 82–86；实验 E551–E570）。
> 本轮纪律：**需求可追溯 + 护盾化训练 + 代理鸿沟审计**。两个灵感恰好补上 v9 的两处"来源性"空白：v9 的六层指标与五维权重仍由工程师手设（需求从哪来？），v9 的策略仍是冻结的启发式/离线产物（策略凭什么改进？）。本轮坚持三条铁律：需求编译只能**收紧**安全、不能放松；强化学习只在**护盾内**改进、只在**双证书**下部署；任一新模块失效即注入 v9 默认值，严格退回 v9，而非行为漂移。

## 0. 直觉与动机

**灵感 1（用户需求分析 → 需求编译器）**
直觉：家庭服务机器人听到的是"别烫到人""动作轻一点""但也要快点"，而系统内部只认 M₀ 间隙、τ_eff 力矩、五维权重。中间缺一层**可审计的翻译**。严谨化：需求不是一句加权口号，而是带类型、带验收测试、带溯源的契约 ρ=(H,W,A,T)。**硬需求 H** 只能是对 M₀/物理约束的收紧（如 clearance 0.15→0.25 m），**软偏好 W** 才进入可交易的五维权重；"快 vs 稳"这类冲突不静默平均，而是给出**不可行证书**与最小冲突集，交还用户澄清。这就是 **P13 需求可追溯律**：没有落到某个指标与某条可执行验收测试的需求，不得进入部署目标。

**灵感 2（强化学习训练 → 安全护盾训练器）**
直觉：v9 部署时已有三道安全网——M₀ 硬检查、AC 中止点、MW 契约退化。可训练时却把这三道网摘掉了，只让策略在仿真里裸奔，再用"离线安全"口头保证。为什么不在训练时就把同一张网装上？SRT 令每个探索动作先过**护盾 S(s,a)** 再进环境，硬违规在构造上为 0；再在**可行策略集 Π_H** 内用约束 RL 优化编译后的软偏好。训练离线/异步，部署只跑冻结策略 + 有界残差。核心是 **P14 训练-部署安全语义同一律**：训练与部署共用**同一份**护盾代码、同一组阈值，而非"仿真近似、部署再补"。

**灵感 3（桥接：代理鸿沟审计）**
直觉：RL 是最擅长钻代理目标空子的优化器；需求编译又必然丢信息（"轻一点"不等于某个 τ_eff 数值）。两者叠加，系统可能**精确地优化了一个不是用户想要的东西**——Goodhart 定律的工程版本。NRA 用留出用户测试集、反事实排序探针、硬需求回归测试估计**代理鸿沟** CG；相关不足或"不可接受轨迹的预测收益反超可接受轨迹"时，拒绝部署并回滚。这就是 **P15 代理鸿沟审计律**。

## 1. 研究问题（轮次升级版）

- **Q1（需求可编译性与可行性）**：如何把自然语言/演示/评分等异质需求，编译为"只能收紧安全"的需求契约 ρ=(H,W,A,T)，并在编译期检出需求冲突与物理不可行，给出可行动的最小冲突集而非静默降级？
- **Q2（护盾训练的等价性与部署证书）**：把 v9 的 M₀+AC+MW 作为训练期护盾，能否使"护盾约束 MDP 的最优解"与"部署期安全策略"在可观测行为上同一？双证书（安全证书 + 需求验收证书）能否给出有限样本下的部署风险上界？
- **Q3（代理鸿沟的可检测边界）**：在用户真实需求只能部分表达的前提下，需求-奖励一致性审计能检测出多大的奖励钻空子？哪些"未表达需求"是原理上不可检测的，系统应如何显式暴露这一残余风险？

## 2. 设计原则（在 P10–P12 基础上新增 P13–P15）

**P13 需求可追溯律（Requirement Traceability, UNC）**
每条用户需求 u 必须编译为三元组 (u, m_u, a_u)：m_u 是 M 中一个可测指标/约束，a_u 是一条可执行验收测试。硬需求集合 H 满足 H ⊇ H₀（H₀ 为 M₀ 与平台物理约束的像），编译算子只允许收紧；无法编译的需求进入"未决池"，不参与部署，但必须向用户回显。需求冲突时输出最小不可满足子集（MUS），禁止加权平均掩盖冲突。

**P14 训练-部署安全语义同一律（Shielded Training, SRT）**
训练 rollout 与部署 rollout 使用同一护盾实现 S（M₀ 硬检查 ∧ AC 块证书/中止点）。护盾把任意策略投影到可行集：π_S = S∘π。约束 RL 只优化 r_soft，硬代价 r_H 由护盾保证为 0。部署策略必须携带双证书：(i) 安全证书——有限样本硬违规率上界 ≤ δ_safe；(ii) 需求证书——验收测试集在留出用户分布上通过且有余量。二者缺一即部署 v9 冻结策略。

**P15 代理鸿沟审计律（Proxy-Gap Audit, NRA）**
部署前与周期性运行一致性审计：用反事实偏好探针估计 r̂ 与用户排序的 Kendall 相关，并计算"钻空子余量" h = max_{τ∉A} r̂(τ) − max_{τ∈A} r̂(τ)，要求 h ≤ 0 且 CG ≥ ρ_min。审计失败 ⇒ 冻结 r̂ 至上一认证版本、停止在线更新并回滚策略；审计通过也不声明"需求已完全满足"，只声明"在已表达需求上无可检测代理鸿沟"。

## 3. 与基线的接口（如何退化）

- UNC 失效或需求不可行 ⇒ H←H₀、W←W_v9、T←空，系统按 v9 手设权重运行；冲突集照常上报，绝不通过放松安全来"修复"需求；
- SRT 不可用或双证书未过 ⇒ π←π_v9（v9 冻结策略）、残差 Δθ≡0，等价 v9 决策；
- NRA 失效 ⇒ r̂ 冻结在最后认证版本，关闭在线奖励更新，等价"只用已审计奖励"；
- 需求漂移超阈 ⇒ 回滚到上一双证书版本，重新编译/重新认证，期间保持 v9 安全级；
- 全部失效 ⇒ 完整退回 v9（ACMD），再退回 v8/v7/v6。

## 4. 预期贡献

1. **需求编译器**：把"用户语言"变成"指标+验收测试+溯源"的可审计契约，编译保序（只收紧），冲突/不可行显式化；
2. **护盾化约束 RL**：训练与部署共享同一安全语义（同一护盾），用双证书把"安全"从训练口号变成部署门槛；
3. **代理鸿沟审计**：给 Goodhart 风险一个可测指标与回滚机制，并诚实划出"未表达需求不可检测"的原理边界；
4. **需求-安全-改进三闭环**：E571–E590 覆盖编译正确性、冲突检测、护盾零违规、双证书误收率、奖励钻空子、有界残差、需求漂移与端到端任务。

## 5. 本轮最大风险

**一句话**：护盾与双证书只能保证"已编译、已验收"的那部分需求，而 RL 会精确地把软偏好优化到代理目标的极值——若用户真实需求中存在**未被表达、未被测试覆盖**的维度，系统会以可证明安全的方式稳定地满足一个错误的目标，即"越优化越偏"的 Goodhart 风险。

## 1. 符号体系增量（定义 540–550）

**新增定义 540（用户需求记录 UserNeedRecord）** 需求的最小可审计单元 u = (id, text, type, modality, target, a_u, conf, prov)。type=hard 的需求必须映射到 M₀ 或平台物理约束的**收紧**；type=soft 的需求映射到五维权重或软层阈值。conf∈[0,1] 为编译置信度，低于 τ_conf=0.7 的需求进入"未决池"，不得影响部署。

**新增定义 541（需求契约 RequirementContract）** ρ=(H,W,A,T)。H 为硬约束集，每条 h=(metric, op, threshold, margin, source)；合法性要求 H ⊇ H₀（只收紧）。W∈Δ⁴ 为五维软权重。A 为可执行验收测试集，每条测试给出通过判据与最小效应量。T 为需求-指标-测试三元组集合，要求**满射覆盖**：每条进入部署的 u 至少对应一个 m_u 与一个 a_u。偏序 ρ₁ ⊑ ρ₂ 当且仅当 H₁⊇H₂ 且 W₁ 在 ρ₂ 的软目标下不更松。

**新增定义 542（需求编译算子 CompileOperator）** Compile(U) 分三阶段：(i) **解析**——结构化抽取 + 人工确认，生成候选 u；(ii) **硬约束校验**——把 hard 需求与 H₀ 做包含/区间检查，拒绝任何放松 M₀ 的需求（返回违规需求而非静默丢弃）；(iii) **软偏好求解**——由成对比较按 Bradley–Terry 估计偏好向量，再欧氏投影到单纯形 Δ⁴，得到 W；若约束求解器证明 H 不可满足，返回最小不可满足子集 C（MUS）与不可行证书 cert_infeas。编译结果必须通过定义 543 的溯源检查才可提交。

**新增定义 543（溯源三元组 TraceabilityTriple）** (u, m_u, a_u)：m_u 为 M 中的可测指标（如 M₁ 的 τ_eff、M₀ 的 dist−d_safe），a_u 为在留出用户场景上可执行的验收测试（脚本化断言 + 效应量门槛）。溯源审计要求：任一部署期目标项都能反查到一条用户需求；任一条被采纳的需求都有测试；无测试的需求不得进入 W 或 H。

**新增定义 544（需求可行性证书 FeasibilityCertificate）** 在带模型误差 δ_model 的仿真器上检验：是否存在 π 使硬违规期望 ≤ δ_model 且 J_soft(π) ≥ J_soft(π_v9) − Δ_regret。可行则签发 cert_feas（附可达集/区间算术证据）；不可行则签发 cert_infeas 与 MUS C，C 的每条成员被单独移除后约束集变为可行（最小性）。可行性只在模型内成立，**不得**外推为真实世界可行。

**新增定义 545（安全护盾 Shield）** 复用 v9 组件构造 S(s,a)：
```
S(s,a) = a                         若 M₀_hard(s,a) ∧ chunk_cert_valid(s,a)
       = a^⊥ = AC.abort_or_safe_stop(s)   否则
```
护盾是幂等投影（S∘S=S）。训练期它过滤探索动作，部署期它过滤策略/残差输出；**同一实现、同一阈值、同一 AC 实例**（P14）。

**新增定义 546（护盾约束 MDP ShieldedCMDP）** M_S=(S,A,P,r_soft,r_H,γ,S)，其中 r_H 为硬违规指示（护盾后恒 0），r_soft 由 ρ 的 W 与 v9 六层指标加权得到。训练目标：
```
max_{π∈Π_H}  J_soft(π) = E[Σ_t γ^t r_soft(s_t, S(s_t, π(·|s_t)))]
s.t.  Π_H = {π : V_H^π = 0}（由护盾构造保证）
```
实现采用约束策略优化（拉格朗日/CPO 形式）+ 保守价值估计（离线数据用 CQL 惩罚），避免对 r̂ 的过度乐观。

**新增定义 547（部署双证书 DeploymentCertificate）** cert_dep=(cert_safe, cert_need, cert_gap)：
- cert_safe：留出安全测试集上 n 次 rollout 的硬违规率 Clopper–Pearson 上界 ≤ δ_safe=0.01（置信 1−α=0.95，Bonferroni 校正多重比较）；
- cert_need：验收测试集 A 全部通过，且软目标相对 π_v9 的效应量 ≥ 预注册门槛；
- cert_gap：CG ≥ ρ_min=0.8 且 h ≤ 0 且 drift_u ≤ τ_drift。
三者同时成立才允许部署，否则部署 π_v9（Level-6）。

**新增定义 548（代理鸿沟 ProxyGap）** 在留出探针集 D_probe 上：
```
CG = 1 − Kendall τ( r̂(τ_i), rank_user(τ_i) )
h  = max_{τ∉A} r̂(τ) − max_{τ∈A} r̂(τ)
```
探针由"可接受轨迹的成对扰动"生成（改变速度/力度/接近方向），避免分布外空想。审计还包含硬需求回归测试：若某条 τ∈A 被判为可接受但实际违反 H，立即判定 cert_gap 失败。

**新增定义 549（有界残差策略 BoundedResidual）** 部署期在线微调只允许 π_θ(s)=π_v9(s)+Δθ(s)，‖Δθ‖≤ε_r 且单步动作偏离 ≤ε_a；Δθ 由 SRT 产出的轻量残差头给出，每日/每班次重认证。残差未认证或运行时偏离超界 ⇒ Δθ←0（中立元），退回纯 π_v9。

**新增定义 550（需求漂移 NeedDrift）** drift_u(t)=D_KL( p̂_t(用户语句/评分) ‖ p_cert )，其中 p̂_t 为最近 W_need=200 条用户交互的经验分布；超过 τ_drift=0.1 触发重编译与重认证，期间强制 Level-6 策略与 v9 权重。

## 2. 形式化定义（要点与升级）

**定义 493（六层指标层级）** 继承 v9：M=(M₀,M₁,M₂,M₃,M_dom,M_SLAM) 不变；本轮只增加"指标 ← 需求"的反向溯源 T。
**定义 496（软证书，v10 升级）** δ_trigger 增加两项：`cert_need valid` 与 `drift_u < τ_drift`，与 v9 五条件同尺度；任一项失效即触发 M₀ 硬检查并禁用残差。

# IP-357 UserNeedCompiler：把用户语言编译为可审计契约
class UserNeedCompiler:
    def __init__(self, parser, h0, tau_conf=0.7, delta_regret=0.05):
        self.parser = parser          # 结构化抽取 + 人工确认接口
        self.h0 = h0                  # M₀/物理约束的像（硬需求下界）
        self.tau_conf = tau_conf

    def compile(self, needs, user_confirm):
        recs = []
        for raw in needs:
            u = self.parser.parse(raw)                 # 定义 540
            if not user_confirm(u):                    # 低置信需求不采纳
                continue
            if u.type == 'hard' and not self._tightens(u, self.h0):
                raise RequirementViolation(u)          # 禁止放松安全（P13）
            if u.conf < self.tau_conf:
                self.pending_pool.append(u); continue  # 未决池，不影响部署
            if not self._has_test(u):
                raise UntraceableRequirement(u)        # 无验收测试不采纳
            recs.append(u)
        H = self._merge_hard([u for u in recs if u.type == 'hard'])
        if not self._feasible(H):                      # 定义 544
            return None, FeasibilityCertificate(conflict=self._mus(H))
        W = self._bradley_terry_to_simplex([u for u in recs if u.type == 'soft'])
        T = [(u, u.target, u.a_u) for u in recs]
        return RequirementContract(H, W, [u.a_u for u in recs], T), None


# IP-358 ShieldedRLTrainer：训练与部署共用同一护盾
class ShieldedRLTrainer:
    def __init__(self, shield, policy_v9, rho, gamma=0.99):
        self.shield = shield          # 与部署同一实例（P14）
        self.pi_v9 = policy_v9
        self.rho = rho

    def rollout(self, state):
        # 探索动作先过护盾：硬违规在构造上为 0（引理 89）
        action = self.pi.explore(state)
        safe_action = self.shield(state, action)
        return self.env.step(safe_action), safe_action

    def train(self, data, iters):
        # 约束策略优化 + 保守价值估计；r_soft 由 ρ 的 W 与六层指标给出
        for _ in range(iters):
            batch = data.sample()
            loss = self._cpo_loss(batch, self.rho.W) \
                 + self._cql_penalty(batch)            # 防 r̂ 过度乐观
            self._update(loss)
        return self._freeze_policy()

    def certify(self, heldout_safety, heldout_need, probe):
        cert_safe = self._cp_upper(heldout_safety, delta=0.01, alpha=0.05)
        cert_need = all(a.passed for a in heldout_need) \
                    and self._effect_size(heldout_need) >= self.rho.min_effect
        cert_gap  = (proxy_gap(self.pi, probe) >= 0.8) and (hacking_margin(self.pi, probe) <= 0)
        if cert_safe and cert_need and cert_gap:
            return DeploymentCertificate(cert_safe, cert_need, cert_gap, self.pi)
        return None                                    # 否则 Level-6：部署 π_v9


# IP-359 NeedRewardAuditor：代理鸿沟与需求漂移审计
class NeedRewardAuditor:
    def __init__(self, r_hat, rho, tau_drift=0.1, rho_min=0.8):
        self.r_hat, self.rho = r_hat, rho
        self.tau_drift, self.rho_min = tau_drift, rho_min

    def audit(self, probe, hard_regression, user_interactions):
        cg = 1 - kendall_tau([self.r_hat(t) for t in probe],
                             [user_rank(t) for t in probe])
        h = max(self.r_hat(t) for t in probe if t not in self.rho.A) \
          - max(self.r_hat(t) for t in probe if t in self.rho.A)
        if hard_regression.failed or cg < self.rho_min or h > 0:
            return AuditResult(pass_=False, freeze=True, rollback=True)
        drift = kl(self._recent(user_interactions), self.rho.cert_dist)
        if drift > self.tau_drift:
            return AuditResult(pass_=False, recompile=True, rollback=True)
        return AuditResult(pass_=True)


# 主闭环集成：MetricVoiceGauge-NSRL（新增部分不占 50Hz 主环）
def metricvoicegauge_round_10(M, s, obs, user_needs=None, ...):

    rho = M.certified_rho or M.rho_v9                # UNC 失效 ⇒ v9 权重
    if M.delta_dom < M.tau_dom and M.risk_slam < M.tau_slam:
        delta = M.residual_head(s) if M.residual_certified else 0.0
    else:

    action = M.pi_v9(s) + clamp(delta, -M.eps_a, M.eps_a)
    action = M.shield(s, action)                     # 与训练共用护盾
    # ---- v9 继承路径不变 ----

    if cycle_idx % M.audit_period == 0:

## 4. 推导

**引理 87（需求编译保安全 / 只收紧）** 设编译合法，即 H ⊇ H₀。则任一满足 ρ 的策略必满足 M₀ 与平台物理约束。证明：H₀ 是 M₀ 与物理约束的像；H 只在其上追加约束（定义 541/542 拒绝放松项），故可行域 ⊆ v9 安全可行域；由 v9 引理 80–81，安全不变式成立。∎

**引理 88（可行性证书的模型内可靠性）** 设仿真器相对真实系统的一致误差 ≤ δ_model。若签发 cert_feas，则存在 π 在真实系统中硬违规率 ≤ δ_model 且 J_soft 不低于 π_v9 至多 Δ_regret；若签发 cert_infeas，则 MUS C 在模型内真实不可满足，且移除 C 中任一元素后可行。证明：(i) 由区间算术/可达集对模型误差的包裹，模型内可行解外推至真实系统至多增加 δ_model 违规；(ii) MUS 的最小性由定义 544 的逐元素重求解直接给出；模型内真值由约束求解器完备性保证。∎（注意：δ_model 的估计误差直接进入部署风险，见引理 90。）

**引理 89（护盾不变式 / 训练零硬违规）** 对任意策略 π，组合策略 π_S=S∘π 的任意 rollout 满足 M₀ 硬约束，且 S 幂等。证明：S 在 M₀_hard 与 AC 证书均通过时才放行，否则输出 a^⊥，而 a^⊥ 依 v9 引理 82(ii) 保证安全停驻；故每步均处安全集，归纳得整条轨迹安全；S∘S=S 由定义 545 的直接分情况得到。∎

**引理 90（训练-部署安全语义同一性）** 若部署使用与训练相同的 S 实现与阈值，且策略冻结，则在同一观测序列上部署轨迹与训练轨迹逐位一致；在真实系统上硬违规率 ≤ δ_model + δ_safe（其中 δ_safe 为 cert_safe 上界）。证明：同一 S、同一 π、同一观测 ⇒ 确定性转移逐位相同；真实系统差异仅来自模型误差 δ_model，叠加有限样本上界 δ_safe。∎（这是"同一性"而非"绝对安全"：它把风险显式隔离到 δ_model。）

**引理 91（双证书有限样本泛化）** 在留出安全测试集上 n 次独立 rollout 零硬违规时，真实违规率的 1−α 置信上界为 1−(α/2)^{1/n}；需求验收测试集大小 m、显著性经 Bonferroni 校正后族错误率 ≤ α。故 cert_dep 成立 ⇒ 部署风险 ≤ 预注册 δ_safe 与需求误收率 α，且随 n,m 增大指数收紧。∎

**引理 92（有界残差的安全与收益饱和）** 若 ‖Δθ‖≤ε_r、单步偏离 ≤ε_a，则在护盾下硬约束仍由引理 89 保持；软目标改进满足 J(π_θ)−J(π_v9) ≤ L·ε_a（L 为 r_soft 的 Lipschitz 常数），故残差收益随 ε_a 线性饱和，不存在"无界在线漂移"。∎

**引理 93（代理鸿沟的可检测边界）** 若用户真实效用 U 在探针集上可被排序表达，且 r̂ 与 U 的 Kendall 相关 < 1−ρ_min，则 NRA 以概率 →1 检出；但若某需求维度**未出现在探针集且未被验收测试覆盖**，则该维度上的钻空子在原理上不可检测。证明：前者由 Kendall 统计量的一致性；后者构造反例：两个仅在未观测维度不同的轨迹在 D_probe 与 A 上分布相同，任何仅依赖 D_probe∪A 的审计都无法区分。∎（引理 93 是本轮对 Goodhart 风险能给出的最强诚实陈述。）

**引理 94（严格退化到 v9）** 关闭 UNC/SRT/NRA 时分别取 ρ←ρ_v9、π←π_v9 与 Δθ≡0、r̂←认证版本且停止更新，则主闭环行为与 v9 逐位一致；再由 v9 引理 83–86 逐级退化到 v8/v7/v6。证明：三处替换均为"注入 v9 常量/冻结策略"，不改变 v9 继承路径的输入集合；MW 契约表新增行以 v9 默认值为 v^⊥，故组合退化正确性由引理 83 传递。∎

## 8. 本轮最大风险

**一句话**：护盾与双证书只能保证"已编译、已验收"的那部分需求，而 RL 会精确地把软偏好优化到代理目标的极值——若用户真实需求中存在**未被表达、未被测试覆盖**的维度，系统会以可证明安全的方式稳定地满足一个错误的目标，即"越优化越偏"的 Goodhart 风险。
