# 第 67 轮（新灵感驱动研究循环 第 2 轮；本轮灵感词：「扩散策略」×「开源生态」）

> 承接声明：第 66 轮已把赛题从「人形安全栈」切到 UniBot 参赛研究（产物 v1，IP-C01~C10）。本轮不重开清单，只沿两个新灵感把**策略层**从一句「开源 VLA + 分块动作头」展开成可执行设计，并对 v1 做一次「按动作头 / 按生态位」的深化与修剪（产物区 v2，C01~C13）。三处核心变化：动作头由「回归或流匹配」二选一改为**快速名义头 + 生成式恢复头的双头**；训练基座由「选一个开源模型」改为**单检查点内的任务专家组合（MoLE）**；多模型分歧由「推理集成」改为**离线校准 OOD 门控**——最后一点是被「单模型」赛道规则逼出来的，也顺手消掉了延迟风险。

## 0. 本轮检索核实（检索日期 2026-11-13）

1. **Diffusion Policy 原文**（Chi et al., RSS 2023, arXiv:2303.04137，本轮已复核）：把 visuomotor policy 写成以观测为条件的动作去噪过程。真正有用的不是「扩散」三个字，而是三点组合——**动作序列预测（action chunking）+ 滚动时域（receding horizon，预测 T_p 步只执行 T_a 步）+ 多峰动作分布**。原文报告：T_a=8 在多数任务最优；T_a 过长显著损失反应性；对最多约 4 步的推理/网络延迟仍能保持峰值性能；位置控制比速度控制更抗延迟。
2. **组件消融**（arXiv:2412.00084，本轮检索）：动作序列执行在多数任务带来 10–20% 提升，但短时域任务（如 Hammer）反而变差；去掉滚动时域在长任务上约降 15%。→ 直接支持「块长必须随任务与扰动自适应」，全局固定块长是错的。
3. **数据格式**（Hugging Face LeRobotDataset v3.0 文档、2025-09 发布博客；官方 unibot 数据集 meta/info.json）：官方 32 个数据集均为 **LeRobotDataset v3.0**——Parquet 低维表格 + 多集共享 MP4 + 关系型元数据；`lerobot >= 0.4.0` 原生支持，可流式读取，不必先落盘解包。
4. **开源 VLA 生态**（Physical Intelligence openpi 仓库；LeRobot 0.4.0 发布博客 2025-10-24；LeRobot/GR00T 版本兼容说明 2026-10-19）：π0 是 **flow-matching** VLA，π0-FAST 是自回归 VLA，π0.5 于 2025-09 发布并强调开放世界泛化；base checkpoint 预训练于 10k+ 小时机器人数据；LeRobot 0.4.0 起集成 pi0/pi0.5，0.6.1 的 `pi05` 与 GR00T N1.7 路径可直接读 v3.0。**版本陷阱**：openpi 原生训练器仍钉在 LeRobot v2.1，直接喂 v3.0 会静默走错加载器或报难以定位的错——这决定预处理工作量（产物 C13）。
5. **赛道规则复核**（任务描述与配置）：通才模型赛道要求**最终一个检查点完成全部 32 个任务**。因此任何「多模型集成」只能用于离线校准、教师蒸馏与数据筛选，不能作为提交时的推理集成。这条约束直接改写了 v1 的 C05 与 C07。
6. **未核实项（下轮首查）**：接口 `cam_*_high` 是否与数据集的 rectified 立体对严格同参；官方数据 `action` 是关节目标还是末端目标（决定流匹配动作头的输出空间与 C06 的深度对齐）；步骤分的精确定义（决定 H 的优化目标）。规则手册仍在飞书登录墙后。

## 1. 直觉（先讲人话）

**灵感 1（扩散策略）：它真正卖的是「多峰 + 分块 + 一个免费算力旋钮」。** 名义操作（把杯子从 A 放到 B）几乎是单峰的，1 步流匹配就够；但**人为干扰后的恢复是多峰的**：物体被推走，你要么继续够、要么后撤重抓、要么换手——这是三个互不相交的成功集。对多峰分布做 L2 回归，等于输出三个模态的均值，往往谁都不像。生成式动作头天然每个 rollout 只选一个模态（commit to one mode），又恰好与接口的 `action_chunk_size`（执行时域）对齐。更关键的是：**去噪/ODE 步数 K 是一个可实时调节的算力旋钮**，它直接改变单次调用延迟与动作质量；而块长 H 只改变「多久重规划一次」。这两个旋钮正交，联合调度才是本轮的技术核心。

**灵感 2（开源生态）：它不是「免费模型」，而是三类可复用资产。** (a) **数据与训练栈**：官方数据是 LeRobot v3.0，π0.5 的 flow-matching 动作头、LeRobot 训练器、HF 检查点全部现成，等于免掉「从零实现 VLA」的数月工程。(b) **共享先验 + 轻量专家**：32 个任务各约 1000 条，单任务不够训大模型，但可在同一个 π0.5 骨干上挂 32 个低秩专家（MoLE），用语言指令稀疏路由——**一个检查点、共享先验、缓解负迁移**，天然合规。(c) **独立训练的检查点 = 免费 OOD 探针**：不同家族（π0.5 flow / OpenVLA 自回归 / GR00T DiT）的独立误差可用于校准「何时该信策略」。但同源机器人数据预训练会让误差高度相关 → 它只测**特异性误差**、测不到共模误差；必须与物理引擎分歧（C07）互补。

**合流 → 本轮核心命题：**
> 把策略层重构成「**一个共享 π0.5 骨干 + 任务 LoRA 专家 + 双动作头**」：名义态走 1–2 步流匹配、长块执行；一旦残差门或轻量不确定性头报警，切到多步生成式恢复头、短块并只采一个完整模态。去噪步数 K 与块长 H 由同一个延迟-反应-步骤分调度器联合决定；开源多检查点只在训练/验收阶段充当 OOD 校准器，最终蒸馏回单检查点。

## 2. 严谨定义

**定义 1（双头策略）** π=(π_fast, π_gen, g)。π_fast 用 1–2 步流匹配给出动作块 Â^{1:H}；π_gen 用 K 步流匹配从 p(A|o,l) 采 M 个候选块，选一个后整块执行（不混均）。门控 g(o)=1[ρ_t>τ_ρ ∨ u_φ(o)>τ_u ∨ D_phys(o)>τ_D]，ρ 为命令-观测残差，u_φ 为轻量不确定度头，D_phys 为双物理引擎分歧。

**定义 2（两个旋钮与真实延迟）** K 为去噪/ODE 步数，H 为执行时域（返回给评测的动作块长度）。单次调用计算 C(K)=c0+c1K。若每 H 步调用一次，平均每步延迟 = C(K)/H，但**单次调用 p99 延迟 ≈ C(K)+排队**。因此：**H 摊薄的是平均延迟，压不下单次 p99；只有 K 能直接压低单次 p99**。若可信度条款看逐步延迟分布，这一区分是硬约束。

**定义 3（多峰恢复）** 受扰后最优动作分布 p(a|o)=Σ_m w_m(o)δ_{a_m}，m∈{continue, retreat, regrasp, replace}。若成功集 S_m 互不相交且凸，则单峰预测 ā=Σ_m w_m a_m 可能满足 ā∉∪S_m（一维反例：±1 等权 → 均值 0，而成功要求 |a|>0.5）。→ 生成式头不是「更高级」，而是**恢复轴上的必要条件**；反之，名义单峰任务上用生成式头是纯浪费。

**定义 4（任务专家组合 MoLE）** 共享骨干 θ0 与 J=32 个低秩专家 {Δθ_j}；语言条件路由器 r(l) 取 top-2 权重，θ_deploy=θ0+Σ_j r_j(l)Δθ_j。部署时仍是一个检查点；训练时可按任务分组并行，推理时只激活两个低秩分支。

**定义 5（离线组合分歧）** 取 M 个尽量跨家族的开源检查点，在探针场景集 P 上计算动作均值分歧 D(o)=1/[M(M−1)]Σ_{i≠j}‖μ_i(o)−μ_j(o)‖²。用它离线标注 P 上的策略不确定度，再蒸馏成轻量头 u_φ(o)，部署时只看单模型。**分歧只在离线用，不做提交时集成。**

**定义 6（双旋钮调度）** 给定单次调用硬预算 τ_max 与扰动先验 P_dist，选 (K,H) 最小化
L(K,H)=a·P_dist·H/2 + b·(T/H)·C(K) + c·r(K) + d·C(K)，
其中 r(K) 为动作误差（随 K 下降）。一阶条件给出
**H*(K)=sqrt( 2·b·T·C(K) / (a·P_dist) )**：
K 越大 → 块应更长以摊薄平均成本；扰动越频繁 → 块应更短。若 τ_max 紧，**优先压 K 直接保住 p99，再调 H**。恢复分支以反应性优先，覆盖 H* 取短块，代价是平均延迟上升但单次 p99 仍由 K 控制。

## 3. 对 v1 的继承与修剪

- **继承**：C01 场景编译器、C02 TwinCal、C03 课程、C06 立体深度、C10 预演门保持 v1 主线；C02 的 trust 仍是「仿真恢复数据能否用于训练」的闸门。
- **深化**：C04 从「扰动预演」升级为「模式标注的恢复数据生成」；C08 从「块长自适应」升级为「K×H 联合调度」；C09 从「端口共享后端」升级为「按去噪步连续批处理」；C05 改为单检查点双头 + MoLE。
- **改向**：C07 不再单独承担 OOD 信号，而作为 C12 的**共模侧补充**；v1 中「多模型分歧直接做推理门控」的写法显式放弃（违反单模型赛道）。
- **修剪**：v1 对「流匹配/回归动作头」的二选一讨论作废，统一为「名义快头 + 恢复慢头」；不再追求一个动作头打满所有任务。

**当前最值得押注：C05+C08 的「双头 × K×H 联合调度」——它同时命中成功率（多峰恢复）、步骤分（块长与重规划）和延迟可信度（K 控 p99）三个评分面，且完全不需要真机就能在 DryRun 上先验证。最大风险一句话：整套策略层收益建立在「多峰恢复优势能在 1–2 步蒸馏后保留」与「跨家族检查点的误差足够去相关」两个假设上；若前者导致模态坍塌、后者被同源预训练污染，则生成式头退化成昂贵回归、OOD 门控失效，本轮新增的训练与调度复杂度将全部变成沉没成本，而接触精密/柔性任务依然原地踏步。**

## 2. 创新点 v2

### 维持项（本轮不动，仅记录接口变化）

- **IP-C01 ScenarioForge**：五轴 SceneSpec 编译器（Gazebo/MuJoCo 双后端）维持 v1。新增：每任务编译一个 **探针集 P**（约 20 场景 × 5 轴），既供 C10 DryRun，也供 C12 计算离线分歧。
- **IP-C02 TwinCal**：数据集驱动的孪生标定与 trust 维持 v1。新增用途：trust 同时门控「该任务的仿真恢复数据能否进 C04/C05 训练」，避免把错误物理的恢复轨迹灌进恢复头。
- **IP-C03 Axis-Bandit**：课程维持，动作空间由「任务×轴」扩为「任务×轴×{fast,gen}」——即 bandit 不只决定采哪些场景，还决定算力花在名义数据还是恢复数据上。
- **IP-C06 StereoPrior**：头部 rectified 立体对 → 度量深度，维持 v1（辅助特征，失败静默降级）。
- **IP-C10 SimDryRun**：提交前预演门维持 v1。新增：DryRun 必须跑 E-C09 的 K×H 前沿，把「延迟-成功率」前沿写入提交报告。

### IP-C04 HumanPerturber v2：模式标注的恢复数据生成

- **动机**：真人干扰后的恢复样本在官方数据里几乎不存在；而恢复恰恰是多峰的（继续/后撤/重抓/换手）。要让恢复头学会多个模态，训练数据必须**显式带模式标签**，不能只给「扰动后的下一帧」。
- **差异**：v1 只生成「干扰→恢复」配对；v2 增加两步：①按扰动类型与任务阶段给恢复段打模式标签 m∈{continue, retreat, regrasp, replace}；②对同一扰动采样多个成功恢复，构成**同一状态下的多模态样本集**，直接监督 C05 的生成头（而不是把多模态平均掉）。
- **可行性**：中高。脚本化扰动 + 仿真特权真值即可；模式标签由恢复轨迹的几何/接触事件自动判定，不需要人工。
- **资源**：脚本与标注 1–2 人周；数据生成复用 C01/C02 管线；仅对 trust 达标的刚性任务开。
- **步骤**：①扰动原语库（推物/抽物/挡相机/碰手臂/换目标位）②阶段触发 ③每扰动跑多次恢复并聚类出模式 ④模式平衡采样（每模式至少 n_min 条）⑤按 C02 trust 过滤后入训练池。
- **风险**：仿真恢复模式与真人偏好不一致（人可能先看再动）；缓解：模式集只保留物理上必然存在的（后撤/重抓），不学真人风格；真机槽只用于验证模式是否可用。

### IP-C05 PolyVLA v2：单检查点 + 任务 MoLE + 双动作头（★ 本轮架构主改）

- **动机**：32 任务 × ~1000 条，单任务数据不足以训大模型；但从零训通用 VLA 又不现实。开源生态给了「强先验骨干」，缺的是**任务专业化与恢复多峰性**。
- **差异**：①**不训新架构**：以 π0.5（flow-matching）为骨干，LeRobot 0.6.1 `pi05` 路径原生读 v3.0；②**一个检查点内的 32 个低秩专家**（MoLE），语言指令 top-2 路由，兼顾共享先验与任务特化，天然满足单模型规则；③**双头**：名义态 1–2 步流匹配、长块；报警态 K 步流匹配、采 M 个模态后 commit to one mode、短块。v1 的「特权教师→学生」保留为训练手段，但教师不再是单独部署的模型。
- **可行性**：高。openpi/LeRobot 检查点、训练器、数据格式均现成；主要成本是 LoRA/MoLE 微调与蒸馏。
- **资源**：8×A100/H100 × 1–2 周起步；部署目标单卡 24G（量化 + 低秩专家）。
- **步骤**：①C13 打通数据 ②按任务/任务簇训 LoRA 专家 ③用多步教师蒸馏 1 步名义头（C11）④用 C04 模式数据训恢复头 ⑤C12 校准门控 ⑥打包单检查点并过 C10 DryRun。
- **风险**：路由器塌缩到少数专家（语言相近的任务挤在一起）；缓解：负载均衡辅助损失 + top-2 + 每专家最小采样率；门控假阳性导致频繁走慢头（→ C08 迟滞与 C12 校准）。

### IP-C07 CrossPhys v2：双引擎分歧（共模侧）

- **动机**：C12 的组合分歧只能测「模型间特异性误差」；若所有开源模型共享同一份错误资产/URDF/预训练偏差，共模误差会被漏掉。物理引擎分歧是独立的第二条信号。
- **差异**：v1 把 CrossPhys 当独立创新点；v2 明确它只作为 C12 的**共模补丁**：D_phys 高的场景不据此换动作，而是**降低该场景分歧信号的可信度并触发人工/真机抽检**。
- **可行性/资源**：复用 C01 双后端，增量约 1× 仿真算力（只对高分任务开）。
- **步骤**：①同种子双引擎 ②轨迹/接触事件分歧度量 ③与 C12 的 D(o) 做 2×2 交叉表 ④只把「双高」场景标为高风险。
- **风险**：两引擎共享同一份错误资产 → 共模照旧；缓解：资产级不确定度由 C02 单独维护。

### IP-C08 SalvageChunk v2：K×H 联合调度（★ 本轮机制主改）

- **动机**：v1 只调块长 H；但真正的延迟旋钮有两个：K 决定**单次调用 p99**，H 决定**平均延迟与反应性**。评测同时看成功率、步骤分、逐步延迟，三者由一个二维调度统一。
- **差异**：①门控由「残差超阈」扩展为「残差 + C12 不确定度 + C07 物理分歧」；②调度器按定义 6 的 H*(K) 解析式给初值，再用 DryRun 校准；③报警时恢复头短块 + 多模态采样，正常时名义头长块 + 可选时间集成（temporal ensembling，扰动时关闭以防滞后）。
- **可行性**：高（纯推理侧 + 恢复数据）。
- **资源**：复用 C05 管线；调度参数在 C10 DryRun 上离线拟合即可，无需真机。
- **步骤**：①离线扫 K×H 前沿（E-C09）拟合约束 ②在线估 P_dist（残差/阶段/不确定度）③查表 + 迟滞（短块至少持续 8 步）④报警时 H 取 min(H*, H_short)，容忍平均延迟上升 ⑤记录每次决策的 (K,H,原因) 供复盘。
- **风险**：门控抖动导致块长振荡，反而降成功率；缓解：双阈值 + 最短持续步数 + 只在块边界切换。

### IP-C09 PortFleet v2：按去噪步连续批处理

- **动机**：v1 的「跨端口动态批」把一次 get_action 当整体批；但生成式动作头的计算是**沿去噪步串行**的，不同端口可以在不同 t 上合并——这正是 LLM continuous batching 的结构。做对了，单卡可稳定服务 N 台机器人且 p99 可控。
- **差异**：①批处理粒度从「请求」变为「去噪步」；②固定 B_max + 准入控制，把活跃请求数钳在 B_max 附近（命题 6）；③每端口独立 reset/历史/随机种子，避免跨端口状态污染；④单检查点（MoLE 路由在批内按端口语言分别计算）。
- **可行性**：高（推理系统工程）。
- **资源**：1 台高显存 GPU 服务器；1–2 人周。
- **步骤**：①请求队列 + 步级调度器 ②B_max 与 τ_max 联合标定 ③过载时拒绝/降级到名义头 1 步 ④延迟监控与熔断 ⑤双机热备。
- **风险**：步级批处理实现复杂，错误合并不同 t 的噪声会产出坏动作；缓解：以请求 id + 步号严格分组，单元测试覆盖乱序与超时。

### IP-C11 ConsistDistill：少步蒸馏且保持模式

- **动机**：生成式恢复头若每块要 16–32 步，单次调用延迟会直接违反可信度条款。必须把多步教师压到 1–2 步，同时**不能把多峰压成均值**（那正是 C05 要避免的病）。
- **差异**：普通一致性蒸馏只对齐单条轨迹；本方案在蒸馏损失中加入**模式保持项**：对同一观测的多个教师模态分别蒸馏，或用拒绝采样保证每个模式都有学生样本覆盖；蒸馏后显式测模式熵与恢复成功率。
- **可行性**：中高；一致性/少步流匹配方法成熟（记忆：Consistency Policy 一类工作，未逐一复核）。
- **资源**：2–4 卡数天。
- **步骤**：①多步教师产出模态集 ②1–2 步学生蒸馏 + 模式覆盖损失 ③离线测模式熵/成功率 ④不达标则恢复头保留 4–8 步（接受更高延迟，但只在报警时发生）。
- **风险**：模式坍塌到最频繁的恢复方式；缓解：模式平衡采样 + 蒸馏后按模式召回率验收；验收不过就不上线少步版本。

### IP-C12 OpenProbe：跨家族检查点离线分歧 → 轻量 OOD 头（★ 本轮信号主改）

- **动机**：真机槽稀缺，无法在线试错；但开源生态有多个独立训练的检查点。它们的动作分歧是**免费的策略不确定度标注**。受单模型规则限制，只能在离线用，但这恰好够用：把分歧蒸馏成部署时的一个轻量头。
- **差异**：①明确「离线校准、单模型部署」的合规定位；②给出可检验的分解 E[D]=2σ²(1−ρ)，据此要求跨家族选型（π0.5 flow / OpenVLA 自回归 / GR00T DiT / Octo 扩散），并**显式测 ρ** 以判断共模污染程度；③与 C07 物理分歧组成二维风险图。
- **可行性**：中高。推理多个开源检查点成本可控（只在探针集上跑一次）；蒸馏头很小。
- **资源**：探针集推理数百 GPU 时；蒸馏单卡数小时。
- **步骤**：①C01 生成探针集 P ②跨家族检查点推理 ③算 D(o) 与成功率下降的相关（E-C12）④蒸馏 u_φ ⑤与 ρ、D_phys 交叉验证 ⑥只保留相关性达标的信号源。
- **风险**：ρ 过高（同源预训练）→ D 测不到 OOD；缓解：把 ρ 作为准入门槛，ρ>0.8 的模型对不参与；改用物理分歧与输入空间密度补足。

### IP-C13 LeRobotNative：v3.0 原生训练栈与版本路由

- **动机**：官方数据是 v3.0，而 openpi 原生训练器仍钉 v2.1；这是最容易吃掉一两周且报错难定位的工程坑。把它做成一条明确路径，是「开源生态」最直接的兑现。
- **差异**：不是新算法，而是**可复现的版本路由与数据完整性门**：优先 LeRobot 0.6.1 的 `pi05`/GR00T N1.7 原生 v3.0 路径；只有必须用 openpi 原生训练器时才做 v3→v2.1 转换，并重算归一化统计。
- **可行性**：高。
- **资源**：1 人周。
- **步骤**：①锁版本（lerobot 0.6.1 + 对应 checkpoint）②加载 v3.0 并校验 episode 数/帧率/相机 key/action 维度 ③跑通单任务过拟合（sanity）④再上 MoLE ⑤记录转换脚本与 norm stats 供复现。
- **风险**：版本漂移；缓解：容器化锁依赖 + 提交前跑数据回归脚本。

```python
# C05 + C08：单检查点双头策略 + K×H 联合调度
class DualHeadPolicy:
    def __init__(self):
        self.fast = FlowHead(steps=1)      # 名义头：1 步，便宜
        self.gen  = FlowHead(steps=16)     # 恢复头：多步，多峰
    def get_action(self, obs):
        o = self.backbone(obs, lora=self.route(obs["observation.language"]))  # MoLE top-2
        r = self.residual_gate(o)          # 命令-观测残差
        u = self.unc_head(o)               # C12 蒸馏出的不确定度
        d = self.crossphys.disagree(o)     # C07 共模侧
        alarm = (r > TAU_R) or (u > TAU_U and d > TAU_D)
        P = 1.0 if alarm else self.p_dist(o)
        K, H = self.schedule(P, TAU_MAX)
        if alarm:
            H = min(H, H_SHORT)            # 反应性优先，覆盖 H*
            cands = [self.gen.sample(o, K=K) for _ in range(M)]
            A = self.commit_one_mode(cands, o)   # 只选一个模态，不混均
        else:
            A = self.fast.sample(o, K=K)         # 可选时间集成
        return self.chunk(A, H)                  # 接口 action_chunk_size = H

    def schedule(self, P, tau_max):
        # 先保 p99：只有 K 直接压低单次调用延迟；H 只摊薄平均
        K = max(k for k in (1, 2, 4, 8, 16) if self.latency(k) <= tau_max)
        H = int(np.clip(np.sqrt(2*B*T*self.cost(K) / (A_COEF*max(P, 1e-3))), 4, 32))
        return K, H
```

```python
def openprobe(probes, ckpts):                 # ckpts 尽量跨家族
    D = {}
    for o in probes:

def distill_uncertainty(student, probes, D, phys, lam=0.5):
    for o in probes:
        target = normalize(D[o]) + lam * normalize(phys.disagree(o))  # 补共模
        loss = mse(student.unc_head(o), target)
        update(student, loss)                  # 部署时只看 student
```

## 4. 命题与推导（接 v1 命题 1–2）

**命题 3（K 与 H 不可互换）** 设 L(K,H)=a·P_dist·H/2 + b·(T/H)·C(K) + c·r(K) + d·C(K)，C(K)=c0+c1K，r 随 K 单调降。对 H 求一阶条件得 **H\*(K)=sqrt(2bTC(K)/(aP_dist))**：K 增大使单次调用更贵，应以更长块摊薄；扰动频率升高使短块更优。但在单次延迟约束 τ_max 下，可行域由 **d·C(K) ≤ τ_max**（p99）与 **b·C(K)/H ≤ τ_avg**（平均）共同决定。推论：**τ_max 紧时先降 K（直接降 p99），H 只影响平均延迟；恢复分支为提高反应性可偏离 H\*，代价是平均延迟而非 p99。**

**命题 4（多峰恢复的必要条件）** 设受扰后 p(a|o)=Σ_m w_m δ_{a_m}，成功集 S_m 两两不交且凸。L2 最优单峰预测为 ā=Σ_m w_m a_m。取一维两模态 a_1=−1,a_2=+1,w_1=w_2=0.5，S_m={a:|a−a_m|≤0.5}，则 ā=0∉S_1∪S_2。故：只要任务存在互斥恢复路径且成功集不重叠，单峰回归的最优解成功率可为 0，而生成式头每 rollout 采一个模态可达正成功率。推论：**生成式头应只用于恢复分支；名义单峰任务用它是无谓延迟。**

**命题 5（组合分歧只测特异性误差）** 令 μ_i=μ*+e_i，e_i 交换、E[e_i]=0、Var(e_i)=σ²、两两相关 ρ。则 E‖μ_i−μ_j‖²=2σ²(1−ρ)，故 E[D]=2σ²(1−ρ)。ρ→1（同源预训练/同批数据）时 D→0，无论 OOD 多严重。推论：**跨家族选型是 C12 有效性的前提；必须实测 ρ，并把 ρ 高的模型对剔除；共模由 C07 物理分歧补。**

**命题 6（步级连续批的 p99 上界）** 设每步批上限 B_max、单批单步耗时 s、去噪 K 步。若活跃请求数 N_active≤B_max，单次调用延迟 ≈ K·s；若 N_active>B_max，p99 近似 K·s·ceil(N_active/B_max)。推论：**稳定 p99 的关键不是提高平均吞吐，而是用准入控制把 N_active 钳在 B_max 附近；无上限的动态批会让尾延迟随负载线性恶化。**
