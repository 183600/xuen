# 第 3 轮迭代（灵感循环 v3：「域随机化」×「实时性」）—— 把时间当作一个域：T-DR 与预算化自适应 DR

> 承接 v2（UIP-01′~15：RHPV-D + Gazebo 神谕 + 扰动恢复数据工厂 + 实时/模块化）。v2 自认的最大风险是「用仿真过拟合仿真」。本轮两个灵感词表面上是在说「多随机化一点、跑快一点」，但重新核对提交接口后，得到一个更尖锐的判断：**这个赛制里最没有被随机化的域不是纹理、不是质量，而是时间本身。** 评测端整块执行开环动作、按块重新观测、并记录逐步延迟与抖动；人为干扰又恰好是「在某个时刻把已完成进度撤回」。因此 v3 的核心不是「加更多视觉 DR」，而是 **T-DR：把观测延迟、执行延迟、块相位、干扰起始相位、撤回速度与撤回深度一起随机化**，并在**固定块长 `T_a` 的硬约束**下重新定义实时性。
>
> 本轮先做两处必须写在前面的事实纠偏（2026-11-13 复核）：① `action_chunk_size` 在握手时固定，`example_env.step()` 对每个动作数组硬校验 `shape == (T_a, …)` 且 `dtype == float32`，所以 v2 UIP-13 的「运行期返回 ≤k 步的块」**不成立**；② `unitree_ros` 中 G1 只有 URDF/MJCF，**没有完整的 Gazebo 控制器配置**（完整配置只列 laikago/aliengo/a1/b1/b2/go1/go2；社区 G1 Gazebo URDF issue #129 仍 open），所以 v2 的「Gazebo 计分神谕」应降级为 **MuJoCo 主、Gazebo 备**。这两条纠偏不是退步，反而把 DR 放到更合适的物理引擎上：MuJoCo 的 MJCF 更适合做质量/摩擦/增益/接触参数的批量随机化。

### 对 v2 的两处修正

- **修正 A（实时性）**：v2 UIP-13 ACS 假设运行期可变块长，接口上不成立。正确的杠杆是：**在握手时选一个全局 `T_a`**，运行期只能在**固定长度块内部**调度内容（速度、对齐、保尾、把不可逆动作推迟到下一块的第一步）。这把「实时性」从「动态改块长」改写成「块边界决策 + 块内安全设计」。
- **修正 B（仿真）**：v2 的 Gazebo 计分神谕依赖一个不存在的 G1 Gazebo 控制器配置。改为 **MuJoCo 主神谕**（官方 MJCF、固定底座、Dex1），Gazebo 仅作备选。这个修正与 DR 天然契合：MuJoCo 的 `mass/friction/damping/gear/contact` 都可以低成本批量随机化，且 headless 并行远易于 Gazebo。

## 1. v2 清单诊断（升级 / 改写 / 封存）

- **升级为「时序版」**：UIP-01′（RHPV-D）→ **UIP-01″ T-ARC**。v2 的「每 k 步核验」在开环契约下实际上只能是「每块核验」；因此把反应下界、检测延迟、撤回相位写进状态机，并用 T-DR 训练。
- **升级为「DR 版」**：UIP-11（GSO）→ **UIP-11′ MuJoCo 神谕 + DR 参数族**；UIP-12（DRF）→ **UIP-12′ 覆盖矩阵驱动的数据工厂**。先定义「随机化哪些轴、随机化到多大、为什么可信」，再生成数据。
- **改写**：UIP-13（ACS）**封存其可变块长部分**，由 **UIP-20 BCS（块内容调度）** 取代；UIP-15（CSG）→ **UIP-15′ 延迟-抖动安全阀**，把「重做」限制在块边界并加迟滞。
- **保留**：UIP-02′（计分步安全网）、UIP-05（语言→可供性）、UIP-08′（多端口延迟工程，升级为 UIP-08″）、UIP-14（模块化技能图）。
- **新增（命中两词）**：**UIP-16 T-DR**（时序域随机化）、**UIP-17 ADR-B**（预算化自适应 DR）、**UIP-18 ADC**（对抗式撤回课程）、**UIP-19 SRL**（现实阶梯校准账本）、**UIP-20 BCS**（块内容调度 / commit-last / safe-tail）。
- **封存**：UIP-04（学习式世界模型 MPC）继续不单列；UIP-10（joint/ee 运行期切换）继续封存。

## 2. 两个灵感词：先直觉，再严谨定义

### 2.1 「域随机化」

**直觉解释。** 域随机化的朴素直觉是：「让策略在成千上万个平行世界里练习，使真实世界只是其中一个样本。」这听起来像数据增强，但在本赛制里它承担的是**覆盖**：公开数据只有 32 个任务、固定机器人、少量场景；测试却明确有未见物品、位置、干扰物、背景、人为干扰五条轴。选手无法在真机上遍历这些轴，只能离线合成覆盖。**但均匀地随机化一切是错的**——它会把容量浪费在物理上不可能、或与真实数据支持相差太远的世界里，还会让「仿真分数」与「真机分数」进一步脱钩。

**严谨定义。** 令域参数

$$\xi=(\xi_{\text{vis}},\xi_{\text{phys}},\xi_{\text{sem}},\xi_{\text{time}})\in\Xi,$$

其中 $\xi_{\text{time}}$ 是本轮新增的时间轴（观测延迟、执行延迟、帧间隔、干扰起始相位、撤回深度、撤回速度）。用 32 个真实数据集估计名义分布 $p_0$ 与可行域 $\Xi_{\text{real}}$。域随机化不是「任意采样」，而是选择一个随机化分布 $p_\phi$，在一个**可信域**内做分布鲁棒优化：

$$\min_\theta\ \max_{p_\phi:\ D_{\mathrm{KL}}(p_\phi\Vert p_0)\le\varepsilon,\ \operatorname{supp}(p_\phi)\subseteq\Xi_{\text{real}}}\ \mathbb{E}_{\xi\sim p_\phi}\big[L(\theta;\xi)\big]+\lambda_c\,C_{\text{cred}}(\pi_\theta),$$

并受训练预算 $B$（GPU 小时 / rollout 数）约束。$C_{\text{cred}}$ 是可信度正则（延迟抖动、动作统计异常）。**一句话：DR 不是数据增强技巧，而是在「可信性约束 + 计算预算」下的分布设计问题。**

### 2.2 「实时性」

**直觉解释。** 实时性不是「跑得快」，而是「有界、可预测、且被块契约量化」。评测端把一整块动作执行完才再次调用 `get_action`；在此期间策略看不到新观测。于是**反应时间被量化到块长 `T_a`**：干扰若发生在块内，最早也要到下一个块边界才可能被看见。更糟的是，观测本身还有延迟，动作执行还有延迟。实时性因此不是工程优化项，而是**与得分直接耦合的安全边界**。

**严谨定义。** 定义盲窗

$$W=T_a+d_{\text{obs}}+d_{\text{exec}},$$

其中 $d_{\text{obs}}$、$d_{\text{exec}}$ 分别为观测与执行延迟（以步计）。若人为撤回事件以速率 $\lambda$ 到达、每次恢复耗时 $r$，则恢复队列稳定的必要条件是

$$\lambda\left(\frac{W}{2}+r\right)<1.$$

若违反，重做队列会发散：策略越「勤奋」地重做，越追不上新的撤回，延迟抖动也越大。给定单次调用开销 $c_{\text{call}}$、单步丢失代价 $c_{\text{loss}}$，一个简化的每步成本为

$$C(T_a)=\frac{c_{\text{call}}}{T_a}+\lambda\,c_{\text{loss}}\left(\frac{T_a+d_{\text{obs}}+d_{\text{exec}}}{2}+r\right),$$

其极小点为

$$T_a^\*=\sqrt{\frac{2c_{\text{call}}}{\lambda\,c_{\text{loss}}}}.$$

这给出可检验的预测：**撤回率高、单步代价大的接触密集任务希望小 `T_a`；远距离搬运希望大 `T_a`。** 但 `T_a` 是全局固定的，所以只能做**任务组合层面的风险加权选择**，并把块内设计（UIP-20）作为补偿。

## 3. 瓶颈假设（更新）

- **H1（最高杠杆）**：v2 已覆盖「语义/视觉/干扰存在性」，但没有覆盖**干扰的时间相位**。若评测中的人为干扰发生在块内，策略的检测延迟由 `T_a` 与延迟决定；**不经 T-DR 训练的策略会在最坏相位上系统性丢步骤分**。因此「相位分层的最坏情况」比「平均成功率」更能预测榜单。
- **H2**：无约束的自适应 DR 会追逐仿真伪难点（穿模、数值爆炸、不可达位姿），必须用真实数据锚点做可信域约束；**DR 的收益应按「真实锚点上的非降 + 结构一致性」验收，而不是按仿真分数验收**。
- **H3**：既然运行期不能改块长，**块内安全设计**（safe-tail、commit-last、速度剖面）是唯一能在开环执行中降低「撤回代价」的手段；它应与验证器联合设计，而不是事后补丁。
- **H4**：真实数据的动作统计（速度、抖动、夹爪开合节律）是免费的**可信度先验**；用它约束合成动作，可以同时降低「动作统计异常」与 sim-to-real 漂移。

## 4. 候选与合并 → v3 清单

围绕两词发散 8 个草案，合并后得到 v3：保留 UIP-02′/05/14，升级 UIP-01″/08″/09′/11′/12′/15′，改写 UIP-13→UIP-20，新增 UIP-16~19。旗舰从「扰动恢复」进一步收窄为 **T-ARC（Temporal-Adversarial Randomized Chunking）**：在**块边界**做进度验证，在**块内**做安全调度，在**训练分布**上随机化时间轴与撤回相位。

**本轮最值得押注**：**UIP-16 T-DR × UIP-18 ADC × UIP-01″ T-ARC** 组成的「时间对齐的扰动恢复」——它不需要新硬件、不违反单模型合规，且直接命中 v2 无法覆盖的「干扰相位」盲区。

## 5. 本轮最大风险

**一句话**：最大的风险是「在错误的时序模型上刷分」——如果真实评测的延迟、干扰相位或 episode 终止条件落在我们假设的 T-DR 支持集之外，那么所有离线收益都不可校准；必须保留真实数据锚点、相位分层验收与在线保守回退，绝不能把仿真里的最坏相位当成真机结论。

## 1. 旗舰深潜：UIP-01″ · T-ARC（Temporal-Adversarial Randomized Chunking）

- **契约事实**：策略每次返回一个形状恰为 `(T_a, …)` 的块，评测端整块执行后才再次调用。因此「每 k 步验证」实际上只能是**每 `T_a` 步验证**；块内没有新观测。
- **机制**：
  1. **块边界验证**：在每次 `get_action` 时，用内部进度头 `V(o_t, l, g)` 判断当前计分步 `g` 的状态 ∈ {`done`,`ongoing`,`regressed`,`fail`}。`regressed` 由「上次已 done 的子目标在视觉/几何上回退」触发，直接对应 `human_*` 的「合上再打开 / 拉上再拉开 / 叠好后翻开 / 拿走」。
  2. **跨块重做**：`regressed` 时不立刻在当前块尾部补救（来不及），而是把「重做计划」放到下一块的**第 0 步**；这样提交下一块时用的是刚看到的最新观测。
  3. **块内 safe-tail**：每块最后 `h` 步降速/保持/柔顺，限制「撤回发生后仍继续执行错误动作」造成的连锁损害。
  4. **commit-last**：把不可逆段（插入、压合、释放、拉链到底）尽量安排在下一块的第 0 步，而不是当前块的尾部；验证通过才提交不可逆动作。
  5. **训练分布**：用 UIP-16 T-DR 随机化延迟/相位，用 UIP-18 ADC 生成合法但最坏的撤回时机；验证时按干扰相位分层报告**最坏桶**，而不是只看平均。
- **与 v2 差异**：v2 假设可在块内多次验证并返回变长块；v3 承认反应被量化到 `T_a`，把「实时性」变成状态机的一等约束，并用块内设计补偿。
- **可行性**：高。`get_action`/`reset`/`metadata` 均在接口内；进度头从主骨干蒸馏，避免外部 VLM 的「单模型」合规风险。
- **资源**：32 个公开数据集（写判据与弱标注）+ 1 张推理卡 + MuJoCo 离线回放；无需额外接口。
- **落地**：① 逐任务对齐 2–5 个计分步与可观测判据；② 实现 done/regressed/fail 的内部进度头；③ 实现块边界状态机 + safe-tail/commit-last；④ 用 UIP-11′ 做离线代理评分；⑤ 用 UIP-19 在真实数据锚点上验收。
- **风险**：误判 `regressed` 会导致「反复重做」→ 用 UIP-15′ 的置信度门限、最大重做次数、迟滞与延迟预算兜底。

## 2. 域随机化的形式化与覆盖矩阵

### 2.1 目标

$$\min_\theta\ \max_{p_\phi:\ D_{\mathrm{KL}}(p_\phi\Vert p_0)\le\varepsilon,\ \operatorname{supp}(p_\phi)\subseteq\Xi_{\text{real}}}\ \mathbb{E}_{\xi\sim p_\phi}\big[L(\theta;\xi)\big]+\lambda_c\,\mathbb{E}\big[\mathrm{LatVar}(\pi_\theta)\big]$$

$$\text{s.t.}\quad \text{training cost}\le B,\qquad \xi=(\xi_{\text{vis}},\xi_{\text{phys}},\xi_{\text{sem}},\xi_{\text{time}}).$$

- $p_0$：由 32 个真实数据集估计的名义分布（相机内参、物体位姿范围、动作速度/抖动统计）。
- $\varepsilon$：可信域半径；太大 → 仿真伪难点，太小 → 覆盖不足。
- $\lambda_c$：可信度权重；对应 README §6 的延迟波动与动作统计规律性。
- $\xi_{\text{time}}$：本轮新增，见 §3。

### 2.2 覆盖矩阵（先设计，再采样）

| 泛化轴 | 真实数据支撑 | 随机化算子 | 代理/锚点 | 主要风险 |
|---|---|---|---|---|
| 未见物品 `unseen_object` | 32 数据集内的物体类别 | 换网格/纹理/尺寸/材质；保持可抓取性 | MuJoCo 碰撞 + 真实动作统计 | 外观与接触参数双重漂移 |
| 位置/朝向 | 真实 episode 的物体位姿 | 工作空间内位姿抖动 + 可达性过滤 | MuJoCo 几何谓词 | 采样到不可达/穿模位姿 |
| 干扰物 | 真实数据中稀疏 | 插入杂物、遮挡、改变摩擦 | MuJoCo + 真实图像锚点 | 遮挡导致验证器误判 |
| 背景/光照 | 少量真实场景 | 纹理/光照/相机外参随机化 | 渲染器 + 真实特征距离 | 光度漂移伤视觉编码器 |
| 人为干扰 `human_*` | **零覆盖** | 合法撤回动作集（开/合/拉/翻/拿走/挪底座）× 时机 × 深度 × 速度 | MuJoCo 脚本化手 + 可选物理代理 | 最大不确定源：形态/时机/语义 |
| **时间（本轮新增）** | 无标签 | $d_{\text{obs}}$、$d_{\text{exec}}$、帧间隔、干扰相位、块内相位 | 评测 stub 复现 + 延迟注入 | 时序模型设定错误 → 全部离线收益不可校准 |

**关键判断**：公开数据在「人为干扰」和「时间」两轴上几乎零覆盖。UIP-12′ 不应平均分配采集预算，而应按**每单位算力能降低的最坏桶风险**分配（UIP-17）。

## 3. UIP-16 T-DR 与 UIP-18 ADC

### 3.1 T-DR：时序采样器

```python
def sample_time(rng, T_a, H, cfg):
    # deployment uses a fixed T_a; training conditions on it
    d_obs   = rng.integers(0, cfg.d_obs_max + 1)      # observation delay, steps
    d_exec  = rng.integers(0, cfg.d_exec_max + 1)     # execution delay, steps
    dt      = rng.uniform(cfg.dt_min, cfg.dt_max)     # frame interval jitter
    s       = rng.uniform(0.0, H)                     # disturbance onset, steps
    phase   = s % T_a                                 # within-block phase
    u       = rng.integers(1, cfg.u_max + 1)          # undo depth, steps
    v       = rng.uniform(cfg.v_min, cfg.v_max)       # undo speed
    drop    = rng.random() < cfg.p_drop               # frame drop
    return dict(d_obs=d_obs, d_exec=d_exec, dt=dt, s=s,
                phase=phase, u=u, v=v, drop=drop)
```

- **训练**：`T_a` 固定为部署值；同时在离线阶段用 `T_a ∈ {1,2,4,8,16}` 训练一个 `T_a`-条件化版本，用于**选块长**（部署仍只用一个固定值）。
- **验证**：按 `phase` 分桶（例如 `[0,T_a/4)`、`[T_a/4,T_a/2)`、`[T_a/2,3T_a/4)`、`[3T_a/4,T_a)`）报告步骤分；**最坏桶**才是主指标。
- **注意**：观测目录没有时间戳，策略无法直接估计 `d_obs`；T-DR 训练的是「对时序不确定鲁棒的行为」，不是「在线估计延迟」。

### 3.2 ADC：合法撤回的对抗课程

```python
class AdversarialUndo:
    def act(self, progress, t, T_a, rng):
        # legal human-like undo verbs only:
        # open, close, pull, flip, remove, move_base
        phase = rng.choice(self.phases)          # onset within/around block
        u     = rng.integers(1, self.u_max + 1)  # undo already-completed steps
        v     = rng.uniform(self.v_min, self.v_max)
        verb  = rng.choice(self.legal_verbs)
        return dict(onset=t + phase, u=u, v=v, verb=verb)

    def update(self, regret, plausibility):
        # alternating update with policy; constrain to human-like support
        self.w *= np.exp(self.eta * (regret - self.beta * plausibility))
        self.w /= self.w.sum()
```

- **课程**：① 单步撤回、靠近块边界；② 单步撤回、最坏相位；③ 多步撤回；④ 混合速度/深度/动词。
- **合法性约束**：只能撤回**已完成**的步骤，只能使用 `human_*` 文本里出现的动词，速度/幅度受人类手部可达范围限制。否则会训练出「对付超人干扰」的伪能力。
- **收益**：把 UIP-01″ 的训练从「平均干扰」推到「最坏相位」，直接优化相位分层指标。

## 4. UIP-17 · ADR-B（预算化自适应域随机化）

```python
class BudgetedADR:
    def __init__(self, axes, p0_anchors, budget_B, eta, beta, d_max):
        self.w = {ax: uniform_bins(ax) for ax in axes}
        self.used = 0

    def sample(self):
        xi = {ax: sample_bin(ax, self.w[ax]) for ax in self.axes}
        xi["time"] = sample_time(...)          # UIP-16
        return xi

    def update(self, rollouts):
        for ax in self.axes:
            for b in self.bins[ax]:
                fail = failure_rate(rollouts, ax, b)
                d    = plausibility_distance(ax, b, self.p0_anchors)
                self.w[ax][b] *= np.exp(self.eta * (fail - self.beta * d))
            self.w[ax] /= self.w[ax].sum()

    def maybe_expand(self):
        for ax in self.axes:
            if self.success(ax) > self.tau and self.plausibility(max_bin(ax)) < self.d_max:
                self.expand(ax, step=self.step)

    def stop(self):
        return self.used >= self.budget_B
```

- **失败驱动**：失败密度高的桶被更多采样；但用 `beta * plausibility` 惩罚离真实锚点太远的桶，避免「追仿真伪难点」。
- **预算**：`B` 以 rollout 数或 GPU 小时计；任何时候都能返回当前最优 checkpoint（anytime）。
- **防塌缩三护栏**：① 真实锚点分数不得下降；② 扩展速率上限；③ 结构一致性（计分步顺序）不得退化。任一违反则冻结/回滚范围。

## 5. UIP-20 · BCS（修正 v2 UIP-13）

- **事实**：`action_chunk_size` 固定，动作数组必须恰为 `(T_a, …)`。所以「自适应块长」作废；可调的是**块内内容**。
- **机制**：
  1. **速度剖面**：块内前段快速运输、后段对准减速；接触密集段用低速度/低增益。
  2. **safe-tail**：最后 `h` 步保持/柔顺/微退，限制撤回后的连锁损害。
  3. **commit-last**：不可逆动作放到下一块第 0 步，验证后再提交。
  4. **全局 `T_a` 选择**：离线用 `T_a` 扫描与任务组合风险加权，最小化

     $$\widehat{\mathbb{E}}\big[\text{score loss}(T_a)\big]+\lambda_c\,\widehat{\mathrm{LatVar}}(T_a),$$

     部署时固定该值；不能用运行期变长块。
- **风险**：safe-tail 会牺牲平均速度；commit-last 可能错过接触时机。必须用 E305/E306 量化「最坏桶收益 vs 平均分代价」。

## 6. UIP-11′ · MuJoCo 计分神谕（纠偏）与 UIP-12′ · DR 数据工厂

### 6.1 为什么是 MuJoCo

- `unitree_ros` 的 G1 有官方 **MJCF**，但完整 Gazebo 控制器配置只覆盖四足；G1 Gazebo issue #129 仍 open。继续把 Gazebo 当主神谕是在错误前提上堆工程。
- MuJoCo 更适合 DR：质量、摩擦、阻尼、armature、增益、接触参数都可批量随机化；headless 并行便宜；固定底座桌面任务不需要行走。
- Gazebo 仅作备选：若社区 URDF 控制器可用，再用于交叉检查。

### 6.2 计分谓词（示例）

```python
def score_step(task, sim):
    s = 0
    if task == "T26_plug_in_ethernet":
        s += 30 if sim.gripper_holds("ethernet") else 0
        s += 30 if sim.gripper_holds("port") else 0
        s += 40 if sim.contacts("rj45", "port") and sim.insert_depth() > D else 0
    if task == "T27_stack_bowls_three":
        s += 30 if sim.bowl_at("bowl1", "center") else 0
        s += 30 if sim.stacked_on("bowl2", "bowl1") else 0
        s += 40 if sim.stacked_on("bowl3", "bowl2") else 0
    return s
```

- **定位**：结构/顺序/恢复的裁判，不是像素级成败的裁判；所有结论标注「代理」。
- **校准**：先在公开真实数据上回放，比较计分步顺序与动作/ee 轨迹；结构一致性低则神谕无效（见 UIP-19）。

### 6.3 UIP-12′：覆盖矩阵驱动的数据工厂

- 按 §2.2 的轴生成数据，但每个轴带**可信域标签**（离真实锚点的距离）与**相位标签**（干扰起始相位、撤回深度）。
- 生成优先级：先补「人为干扰 × 时间相位」，再补「未见物品/位置」，最后才是背景/光照（因为前者对步骤分边际收益最大）。
- 输出三元组：`(干扰前状态, 撤回动作, 恢复动作)`；并记录其 `phase/u/v`，供相位分层训练与验证。

## 7. UIP-19 · SRL（现实阶梯校准账本）

| 阶梯 | 来源 | 用途 | 能证明什么 |
|---|---|---|---|
| L0 | 32 个公开真实数据集 | 名义分布 $p_0$、动作统计先验、回放锚点 | 真实动作/轨迹的形态与范围 |
| L1 | MuJoCo（MJCF）+ DR | 批量 rollout、计分步代理、扰动课程 | 结构/顺序/恢复的相对优劣 |
| L2 | 低成本物理代理（可选：平行夹爪 + 脚本化人手） | 干扰时机/接触的物理验证 | 时序与接触的定性趋势 |
| L3 | 真实 G1 评测（若可用） | 最终锚点 | 真正的成功率与步骤分 |

- **指标**：① 结构差（计分步顺序一致率）；② 运动学差（动作/ee 轨迹 MMD）；③ 视觉差（特征距离/FID）；④ 分数差（代理分 vs 真实分）。
- **决策规则**：只有当结构差与非干扰锚点分数**不退化**时，才接受 DR 范围扩展；若仿真分数上升而锚点差扩大，判定为「仿真过拟合」并回滚。
- **诚实边界**：公开数据没有人为干扰，L0 不能验证干扰恢复；因此所有干扰结论只能标为「L1/L2 代理」，不能宣称真机有效。

## 8. 实时工程：UIP-08″ 与 UIP-15′

### 8.1 UIP-08″ · LAT-ENG

- **投机预计算**：评测端执行当前块时存在空闲窗口；用当前动作块与状态预测下一观测，预生成候选下一块。真正的 `get_action` 到来时，只做一致性校验与小幅修正，压低尾延迟。
- **一致性校验**：比较预测观测与真实观测的 ee/关节/图像特征；偏差超阈值则回退到保守块（形状仍为 `(T_a,…)`）。
- **每端口隔离**：共享模型但每端口独立 KV/历史/验证器状态；批处理只做无状态融合，避免跨 episode 污染。
- **载荷削减**：只声明必要观测键、少堆叠帧、适度降分辨率；每张图都是一张 JPEG，堆叠直接抬延迟。

### 8.2 UIP-15′ · CSG-L

- **块边界重做**：所有 `regressed/fail` 的重做计划只跨块生效，避免块内动作突变。
- **迟滞**：连续两次同向证据才升级为 `regressed`；一次反向证据只降速，不立即重做，防振荡。
- **预算**：每次调用延迟预算 + 每 episode 重做次数上限 + 抖动上限；超预算则退回「保前置、放弃末步」的保守策略。
- **动作规律性**：jerk 限制与动作平滑；避免统计异常被可信度口径惩罚。

## 9. 推导：块长—反应—可信度三角

1. **盲窗**：$W=T_a+d_{\text{obs}}+d_{\text{exec}}$。
2. **反应量化**：干扰在块内发生，最早在下一个块边界被看见；若观测还延迟，则可能再顺延一块。
3. **相位覆盖率**：若起始相位在块内近似均匀，则检测延迟 $\delta\sim U(0,W)$，覆盖率

   $$P(\delta\le\delta_{\max})=\min\!\left(1,\frac{\delta_{\max}}{W}\right).$$

   要在 $1-\varepsilon$ 概率下覆盖 $\delta_{\max}$，需

   $$W\le\frac{\delta_{\max}}{1-\varepsilon}.$$

   例：$\delta_{\max}=0.5$ s、$\varepsilon=0.05$、30 Hz 控制 ⇒ $W\lesssim 15.8$ 步；扣除延迟后，`T_a` 通常应落在个位数到十几步。
4. **恢复稳定性**：$\lambda(W/2+r)<1$；违反则重做队列发散。
5. **块长最优（示意）**：$T_a^\*=\sqrt{2c_{\text{call}}/(\lambda c_{\text{loss}})}$。
6. **可检验预测**：① 接触密集/高撤回率任务的最优 `T_a` 小于运输任务；② 相位分层的最坏桶比平均分更能区分有无 T-DR；③ 过度扩张 DR 范围会先提升仿真分、后拉大真实锚点差。

## 11. 合规与风险

- **单模型**：进度头、技能头、验证器全部共享一条骨干；不使用外部 VLM 在线服务，避免「非单模型」判定。
- **接口红线**：动作形状严格 `(T_a,…)`、`dtype=float32`、token 双处携带、N 端口恰好匹配、每端口状态隔离。
- **可信度**：延迟平滑、动作统计规律、无异常离群；投机预计算不得造成返回块长度/形状不一致。
- **仿真过拟合**：DR 范围扩张必须通过 UIP-19 的锚点检查；禁止只报仿真分数。
- **最大不确定性**：人为干扰与真实时序分布均无公开标签；T-DR/ADC 的「真实支持集」只能靠代理与保守先验，不能自证。

## 13. 本轮最大风险与押注

**一句话**：最大的风险是「时序模型设定错误」——若真实延迟/干扰相位/终止条件超出 T-DR 与 ADC 的合法支持集，仿真里的最坏桶优化会变成自我安慰；必须用真实锚点、相位分层验收与保守回退把它钉住。

**→ 押注：UIP-16（T-DR）× UIP-18（ADC）× UIP-01″（T-ARC）**。理由：它把 v2 无法覆盖的「干扰时间相位」变成可训练、可验收的分布；全部落在选手 API 与离线算力之内，且不依赖尚未公开的评测手册。
