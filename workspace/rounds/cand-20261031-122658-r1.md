# 第 13 轮（新循环第 1 轮）· GUARD-SERVO：给 CHUNK-SERVO 加一层「双目虚拟 LiDAR + 扩散不确定性 + CBF 安全盾」

> 日期：**2026-10-31（UTC）**。灵感词：**安全交互**、**扩散策略**、**激光雷达**。
> 承接：第 10 轮 **FACT-VLA**（相位化 BC、CAC 柔顺执行、EGP 证据门控）、第 11 轮 **GEO-RESIDUAL**（动作条件化残差、米制表面距离、编辑检测）、第 12 轮 **CHUNK-SERVO**（30 步 VLA 规划 + 5 步确定性视觉伺服 + 演示检索相对目标 + 数字孪生标定 + 竞赛组合）。
> 本轮不推倒 CHUNK-SERVO，而是补上它最危险的空白：**伺服只对“目标”闭环，不对“人”和“障碍”闭环；VLA 只给一个样本，不知道自己有多不确定；编辑检测只用于事后恢复，不用于事前约束。**

## 0. 一句话

**把官方 WLA 的扩散动作头当成一个分布而不是一个点：用同一 checkpoint 的多采样/跨计划一致性估计不确定性；用头部双目构造一台“窄基线虚拟 LiDAR”，实时生成米制安全场；用一个确定性的 CBF 安全盾把每个 5 步执行块投影到安全集，并在人进入工作区时先让、再重定位、再恢复。VLA 仍是唯一学习模型，安全盾不是第二个模型，而是一个可证明的约束层。**

一句话对比上一轮：第 12 轮把“最后 3 厘米”从开环变成闭环；本轮让这个闭环**在人的旁边仍然敢动，但在人靠近时知道什么时候不该动**。

## 1. 直觉：三个词其实在说同一件事

### 1.1 安全交互：不是加一个碰撞检测，而是把“人”放进控制约束

第 12 轮的 CHUNK-SERVO 已经把执行周期从 1 秒压到 167ms，但它优化的目标仍然是“夹爪到目标的相对位姿”。它没有回答三个安全问题：

1. **人进入工作区怎么办？** 第 12 轮的编辑检测可以事后发现“场景动了”，但发现时机器人可能已经撞上去了。
2. **人把目标物移走/拿走怎么办？** 相对目标会失效，VLA 的旧计划会 stale；没有“让—重定位—恢复”的协议，机器人会对着空气执行。
3. **没有人干扰时，机器人自己会不会撞桌子、撞旁边的杯子、把试管捏碎？** 5 步伺服只对目标闭环，没有对“非目标障碍”和“夹爪过度闭合”的约束。

赛事规则里，人为干扰是 5 类泛化轴之一，每个任务 10 次里有 2 次，占 **20%**；单次真机上限 180 秒。API 只给四路 RGB + 本体状态，**没有 depth、camera_info、force/torque、tactile**。这意味着安全不能靠力控，也不能靠第二个学习模型；只能靠**几何 + 本体 + 确定性控制**。

所以“安全交互”在本轮的定义是：

> 不是让机器人变慢，而是让机器人有一个**可证明的硬约束**：在硬障碍（人、非目标高物体、自身、工作区边界）之外保持安全距离；在软对象（桌面、目标物、可变形物体）上允许接触，但限制速度、夹持行程和接触法向；在人介入时执行“让—等—重定位—恢复”，而不是硬推。

### 1.2 扩散策略：不是再训一个策略，而是利用已有 DiT 头的分布

官方 UnifoLM-WLA-1.0 的动作专家本身就是扩散式的：默认 4 步去噪、30 步 chunk、30Hz。第 12 轮把它当成一个确定性函数用：采样一次，拿一个 30 步 plan 去执行。这是浪费。

扩散策略的本质是 \(p_\theta(A\mid o)\)，不是单个 \(A\)。它至少给我们两个免费信号：

1. **空间一致性**：同一观测、不同噪声种子采样 \(M\) 次，得到 \(M\) 条动作 chunk。如果它们彼此接近，策略“知道该怎么做”；如果它们分叉成多个 mode，策略“在犹豫”。不需要新权重，只需要同一个 checkpoint 多次前向。
2. **时间一致性**：相邻两次 plan 在重叠时间窗上的预测应该一致。如果不一致，说明新观测让策略改变了主意——这本身就是一个不确定性信号。它只需要一次前向，成本几乎为零。

注意：这不是“集成多个模型”，而是**同一个扩散模型的蒙特卡洛采样**；不是第二个学习策略，而是对已有策略分布的读取。合规上属于“同一 checkpoint 的特征/采样”，比加载一个残差网络安全得多。

更妙的是：**扩散策略的多模态性正好对应安全决策**。在“绕左/绕右/停”三个 mode 之间，均值可能是一条撞向中间障碍的轨迹；medoid（到其他样本平均距离最小的样本）才是安全的代表。第 12 轮如果直接对多个样本取平均，会制造一个谁都没采到的“中间动作”；本轮明确用 medoid，而不是均值。

### 1.3 激光雷达：API 没有 LiDAR，但双目就是一台窄基线 LiDAR

G1 机器人可能装有 Livox Mid-360 之类的 LiDAR，但**挑战赛提交 API 的观测里没有 LiDAR，也没有 depth**。所以本轮不假设有激光雷达，而是把头部双目当成一台“虚拟 LiDAR”：

- 头双目已标定：基线 **58.2526 mm**，\(f_x\approx 282.37\) px，`rectified: true`；
- 0.5–1.0 m 工作距离上视差约 **16–33 px**，亚像素匹配可给出毫米到厘米级深度；
- 480×640 双目下采样到 240×320 做 SGBM，单帧 CPU 约 10–20ms，足够 10–30Hz 的安全场更新；
- 点云变换到 base 系后，可以做**静态地图 + 动态簇 + 目标掩码**，这正是 LiDAR 安全层的经典做法，只是点云源换成了双目。

如果未来官方 API 暴露 LiDAR 或 depth，SSF（Stereo Safety Field）只需要替换点云源，算法不变。这是“激光雷达”这个词的正确用法：**借它的几何安全范式，不假装 API 有它**。

## 2. 诊断：CHUNK-SERVO 的三个缺口

把一次人机共处失败拆开：

```text
t0: 人进入工作区 / 手伸向目标物
t0+0.1s: VLA 还在用旧观测规划；它不知道“人”这件事
t0+0.1s … t0+0.3s: 5 步伺服继续朝目标走
t0+0.3s: 机器人碰到人，或者人把目标拿走
t0+0.4s: 编辑检测才发现“场景动了”
```

三个缺口：

1. **反馈对象缺口**：CHUNK-SERVO 的误差 \(e(t)\) 是夹爪到目标的相对位姿；没有一项是“到人的距离”。
2. **不确定性缺口**：VLA 只给一个 plan；执行层不知道这个 plan 是“很确定”还是“在三个 mode 之间犹豫”。高不确定性时继续按 5 步执行，是不安全的。
3. **约束缺口**：编辑检测是后验的、恢复式的；它没有把“人/障碍”变成一个**事前**约束。碰撞不需要 1 秒，1 帧就够。

第 12 轮的三个“1 秒”是规划、推理、恢复；本轮要加的是第 0 个“1 秒”——**从世界变化到控制约束生效的时间**。目标是把 \(T_{react}\) 压到 \(H_{eff}/f_c + \tau_{percept} + \tau_{comm}\)，在最保守时 \(H_{eff}=1\)、30Hz、感知 50ms、通信 100ms，约 **183ms**。

## 3. 提案：GUARD-SERVO

**GUARD-SERVO** = CHUNK-SERVO + 三个新模块：

| 模块 | 全称 | 做什么 | 不做什么 |
|---|---|---|---|
| **DCM** | Diffusion Consistency Monitor | 用扩散头多采样/跨计划一致性估计不确定性 \(u_t\)；选 medoid 作为名义 plan | 不训练第二个模型；不对多个 mode 取平均 |
| **SSF** | Stereo Safety Field | 头部双目 → 点云 → 静态/动态分离 → 目标掩码 → 到硬/软障碍的米制距离 | 不假设有 LiDAR/depth；不做语义分割网络 |
| **CSR** | CBF Shield + Risk-adaptive scheduler | 把每个 5 步块投影到 certified safe set；安全停靠；让行/恢复；按风险调速度/增益/有效前缀 | 不改变 API 的固定 chunk size；不做力控（没有力传感） |

### 3.1 总架构

```text
                    ┌─────────────────────────────────────────┐
                    │ Evaluator (N ports 8765..8765+N-1)      │
                    └──────────────────┬──────────────────────┘
                                       │ obs / action chunk
                                       ▼
                    ┌─────────────────────────────────────────┐
                    │ Per-port PolicyService (CPU)            │
                    │  ├─ CHUNK-SERVO: plan cache + servo     │
                    │  ├─ DCM: diffusion consistency          │
                    │  ├─ SSF: stereo -> safety field         │
                    │  ├─ CSR: certified shield + scheduler   │
                    │  └─ action adapter (WLA 54D -> API 21D) │
                    └──────────────────┬──────────────────────┘
                                       │ async, batched
                                       ▼
                    ┌─────────────────────────────────────────┐
                    │ Shared VLA server (GPU)                 │
                    │  UnifoLM-WLA-1.0, diffusion head, 30    │
                    └─────────────────────────────────────────┘
```

- VLA 仍只在 GPU 上跑一份；DCM 的多采样是对**动作头**的批处理，不是多模型。
- SSF/CSR 全在 CPU，每端口独立；不抢 GPU。
- API 的 `action_chunk_size` 固定为 5；CSR 内部可以只执行前 \(H_{eff}\le5\) 步，剩余步用**安全减速/保持**填充，因此不需要改 API 的 chunk size。

```text

  │
  ├─ SSF: 双目深度 → base 系点云 → 动态簇/静态地图/目标掩码
  │        → D_hard(ee), D_soft(table/target), D_self
  │
  ├─ DCM: 新 plan 与旧 plan 重叠段比较；可选 M 次采样
  │        → u_t（0=确定，1=犹豫）
  │
  ├─ CHUNK-SERVO: a_ff = plan[0:5]；e = servo_error(obs, goal)
  │        → a_nom = compose(a_ff, Δ)

  │        → H_eff, speed_scale, gain_scale
  │        → 逐步 certified projection / 安全停靠 / 让行
  │
  └─ adapter: 5 步 absolute EE + gripper + pivot → API
```

### 3.3 安全场：硬约束与软约束分开

这是本轮最关键的设计细节。**不能把整个场景都当硬障碍**，否则机器人不敢碰杯子、不敢插孔；也不能只把“人”当障碍，否则会撞桌子、撞旁边的试管。安全场分三层：

| 层 | 对象 | 约束 | 目的 |
|---|---|---|---|
| **硬障碍** | 人/动态簇、非目标高物体、机器人自身、工作区边界 | 安全距离 \(d_{safe}\)，certified ball，不可违反 | 不撞人、不撞倒、不越界 |
| **软对象** | 桌面、目标物/受器、可变形物体、低矮物体 | 速度上限、最小高度、夹持行程上限、接触法向缩幅 | 允许任务接触，但不砸、不捏碎 |
| **目标掩码** | 当前阶段要操作的物体/受器 | 从硬障碍集合中排除；从演示检索得到 3D box；人进入时硬障碍优先 | 让“有意接触”成为合法动作 |

形式化地，硬障碍集合：

```math
\mathcal{O}_{\mathrm{hard}}(t)=\mathcal{O}_{\mathrm{dyn}}(t)\cup
\left(\mathcal{O}_{\mathrm{static}}^{\mathrm{tall}}(t)\setminus\mathcal{T}(t)\right),
```

其中 \(\mathcal{T}(t)\) 是当前目标/受器的 3D 区域。硬约束是

```math
D_{\mathrm{hard}}(p)=\min_{o\in\mathcal{O}_{\mathrm{hard}}}\|p-o\|\ge d_{\mathrm{safe}}.
```

软约束包括：

```math
p_z\ge z_{\mathrm{table}}+h_{\min},\qquad
\|g_{t+1}-g_t\|\le \delta_g,\qquad
g_t\le g_{\max}(\hat{w}_{\mathrm{obj}}).
```

这样，机器人可以在目标物上做插入/挂/叠/拉链，但不会把人、旁边的杯子和自己的另一只手臂当成可穿越空间。

### 3.4 CBF 安全盾：一个可证明的球投影

对每个执行步 \(k\)，令 \(h_k=D_{\mathrm{hard}}(p_k)-d_{\mathrm{safe}}\)。距离函数是 1-Lipschitz：

```math
|D(x)-D(y)|\le \|x-y\|.
```

因此，如果步长满足

```math
\|\Delta p_k\|\le \alpha h_k,\qquad 0<\alpha<1,
```

就有

```math
h_{k+1}=D(p_k+\Delta p_k)-d_{\mathrm{safe}}
\ge D(p_k)-\|\Delta p_k\|-d_{\mathrm{safe}}
\ge (1-\alpha)h_k\ge 0.
```

这是一个**充分**安全条件，而且投影极其便宜：

```math
\Delta p_k^{\mathrm{safe}}=
\begin{cases}
\Delta p_k^{\mathrm{nom}}, & \|\Delta p_k^{\mathrm{nom}}\|\le r_k,\\[4pt]
r_k\dfrac{\Delta p_k^{\mathrm{nom}}}{\|\Delta p_k^{\mathrm{nom}}\|}, & \text{否则},
\end{cases}
\qquad r_k=\alpha h_k.
```

它是到半径 \(r_k\) 球上的最近点投影：名义步在球内时**完全不改**（透明性），在球外时只做最小必要缩放。再加一个速度-分离约束：

```math
v_{\max}(D)=\min\left(v_0,\frac{D-d_{\mathrm{safe}}}{T_{\mathrm{react}}}\right),
\qquad
\|\Delta p_k\|\le v_{\max}(D_k)\Delta t.
```

这就是 ISO/TS 15066 速度-分离监控的离散版本。人越近，允许速度越低；不是简单“一刀切减速”。

> 注意：\(h_k\) 是**到最近硬障碍点**的距离。夹爪/前臂有体积，实际使用 \(d_{\mathrm{safe}}=d_{\mathrm{margin}}+r_{\mathrm{gripper}}+e_{\mathrm{depth}}\)，其中 \(e_{\mathrm{depth}}\) 是双目深度误差上界。这样球投影保证的是“膨胀后的机器人点”不进入障碍；是保守的，但不是空话。

### 3.5 风险自适应：不确定性只调速度/前缀，不动硬约束

把风险写成 noisy-OR：

```math
r_t=1-(1-\tilde u_t)(1-\tilde d_t)(1-\tilde e_t),
```

- \(\tilde u_t\)：DCM 不确定性，归一化到 \([0,1]\)；
- \(\tilde d_t=\mathrm{clip}(1-D_{\mathrm{dyn}}/d_{\mathrm{warn}},0,1)\)：动态障碍接近度；
- \(\tilde e_t\)：跟踪残差 \(r_{\mathrm{track}}=\|p_{ee}^{\mathrm{obs}}-p_{ee}^{\mathrm{cmd}}\|\) 的归一化——没有力传感器时，这是“被挡住/被人抓住/滑移”的代理。

调度：

| 风险 | 状态 | 有效前缀 \(H_{\mathrm{eff}}\) | 速度 | 伺服增益 |
|---|---|---:|---:|---:|
| \(r<r_1\) | NORMAL | 5 | 1.0 | 1.0 |
| \(r_1\le r<r_2\) | CAUTIOUS | 3 | 0.6 | 0.7 |
| \(r\ge r_2\) | YIELD / SAFE_STOP | 1 | 0 | — |

关键：**不确定性只改变“执行多长、走多快”，不改变硬约束**。即使 DCM 完全失效，CBF 仍然保证硬障碍安全；这是两个正交的安全层。

### 3.6 让行—重定位—恢复

```text
检测到动态簇进入 d_yield（人/手/移动物体）
        │
        ▼
YIELD: 停；保持；继续观察；不追人手
        │
        ├─ 人离开 T_clear（0.5s）→ 目标未移动 → 恢复旧计划
        │
        ├─ 人移动了目标 → 目标静止 T_static（0.5s）
        │       → 双目 + 演示检索重定位 → 更新 goal → 重规划
        │
        └─ 人拿走目标 / 超过 T_wait（5s）→ 优雅失败，不超 180s
```

“安全交互”不是“看到人就停”，而是**让行之后还能继续**。这需要把第 11 轮的编辑检测升级成“米制动态簇 + 目标重定位”，而不是像素残差。

### 3.7 固定 chunk size 下的“有效前缀”

API 的 `action_chunk_size` 是提交时固定的，评测端会顺序执行返回的 5 步。CSR 不能改变这个长度，但可以改变**内容**：

- 正常：5 步都是名义动作；
- 谨慎：前 3 步名义动作，后 2 步用减速/保持填充；
- 停止：第 1 步开始减速，后 4 步保持；
- 让行：5 步都保持，但 `get_action` 仍快速返回，评测端下一轮再问。

这不是钻规则空子，而是**在固定接口下实现可变执行前缀**。下一轮 `get_action` 会重新看世界，所以“提前停”不会丢反馈。

## 4. 与第 12 轮的关系：保留、升级、剪枝

**保留**：

- 30 步 VLA 规划 + 5 步执行的双频结构；
- 演示检索的相对目标 \(T_{\mathrm{target}\to ee}^*\)；
- 确定性视觉伺服（IBVS/PBVS 混合）；
- 数字孪生只做标定/风洞；
- 单任务不计分通道和 \(q_t\times\Delta/\mathrm{cost}\) 任务组合；
- 单模型合规：VLA 是唯一学习模型。

**升级**：

| 第 12 轮 | 第 13 轮 |
|---|---|
| 编辑检测只用于事后恢复 | 动态簇 + 米制安全场，事前约束 |
| 5 步伺服只对目标闭环 | 5 步块同时受硬障碍/软对象约束 |
| VLA 单样本 plan | DCM 多采样/跨计划一致性 |
| 固定 5 步执行 | 固定 5 步 chunk，内部可变有效前缀 |
| 接触段法向缩幅 | 硬/软障碍分离 + 夹持行程上限 + 跟踪残差 |
| 任务组合按最后 3 厘米 | 任务组合增加“安全临界/人为干扰”维度 |

**剪枝**：

- 不再把“力/触觉闭环”列为近期目标——API 没有；
- 不加载语义分割/第二个检测网络——单模型风险，且动态簇用几何就够；
- 不做 360° 安全承诺——头部双目有 FOV 盲区，只承诺视场内 + 限速；
- 不做完整 6D 物体位姿网络——目标掩码用演示检索 + 局部 ICP/几何；
- 不做“为了安全把速度全局降到很低”——那会拖垮 80% 的正常 trial；只在硬障碍附近降速。

## 5. 预期收益与实验门

### 5.1 收益算术（先验，不是承诺）

- 人为干扰轴占 **20%**。如果让行/恢复把 human 轴从 \(p_h\) 提到 \(p_h+\Delta_h\)，全局约 \(+0.2\Delta_h\)。\(\Delta_h=10\)pp → **+2pp**。
- 接触任务如果因为限速/夹持行程减少“撞飞/捏碎/过冲”，10 个 A 档任务各 +5pp → \(10/32\times5\approx\) **+1.6pp**。
- 正常 trial 如果安全盾完全透明，成本接近 0；如果过度保守，可能 **-2～-5pp**。这是本轮最大的不确定性。
- 现实预期：**+1～+4pp**，且必须用配对 A/B 证明；不做“+10pp”的承诺。

### 5.2 门 S0–S5

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| **S0** | 双目安全场是否可用？ | 0.3–1.0m 深度误差 ≤1cm；动态簇检测延迟 ≤100ms；静态场景误报 ≤1% | 只做视场内粗安全场；关闭硬 CBF，保留限速 |
| **S1** | 扩散不确定性是否校准？ | 与动作误差/失败相关，AUROC ≥0.70；多采样开销 ≤1.5× 动作头 | 只用时间一致性；或关闭 DCM，固定谨慎速度 |
| **S2** | 仿真安全盾是否有效？ | 500 次脚本化人手接近零碰撞；无人工况成功率下降 ≤5pp；自由空间干预率 ≤10% | 降增益/缩硬障碍集合；只保留人-停 |
| **S3** | 真机单任务是否不回归？ | 5 任务 ×5 次 A/B：零碰撞；成功率不降 >5pp；至少 2 个任务 human 轴 +10pp | 回退 CHUNK-SERVO + 全局限速 |
| **S4** | 延迟是否可接受？ | p99 ≤150ms；timeout 不升；N 端口无串扰 | 降双目频率/分辨率；关多采样 |
| **S5** | 消融是否支持因果？ | CBF on > off（安全）；DCM on > off（恢复）；硬/软分离 > 全硬 | 保留有效部分，砍掉无效部分 |

所有门先在离线回放和单任务不计分通道上过；S2/S3 不过，不烧正式 320 trials。

## 6. 最大风险（一句话）

**在无 LiDAR、无力/触觉、腕部无内参、头部双目还有 FOV 盲区的条件下，安全场和扩散不确定性都可能误报；一旦安全盾在 80% 的正常 trial 上过度保守，它就会把 CHUNK-SERVO 的成功率拖低——本轮最大的风险不是撞人，而是“为了不撞人而不敢做”。**

## 0. 结论与边界

### 0.1 一句话结论

官方 WLA 的扩散动作头给的是动作分布，不是单个动作；头部双目给的是米制点云，不是只有 RGB。GUARD-SERVO 用**同一 checkpoint 的采样一致性**估计不确定性，用**双目虚拟 LiDAR**构造硬/软分离的安全场，用**确定性的 certified ball 投影 + 速度-分离约束 + 让行/重定位/恢复**把每个 5 步块投影到安全集。它不新增学习模型，不改变 API 的固定 chunk size，也不假设 API 有 LiDAR/depth/force。预期收益主要来自人为干扰轴（20%）和接触任务 catastrophic failure 的减少；最大风险是安全层过度保守，拖低 80% 的正常 trial。

## 2. 问题形式化

### 2.1 约束 MDP 与安全成功率

任务 \(t\) 的官方成功率：

```math
p_t=\frac{1}{10}\sum_{j=1}^{10}y_{t,j},\qquad y_{t,j}\in\{0,1\},
\qquad
S=\frac{1}{32}\sum_{t=1}^{32}p_t.
```

安全层把每次 trial 变成一个约束优化：

```math
\max_{\pi}\ \mathbb{E}[y]
\quad \text{s.t.}\quad
\mathbb{E}[c]\le \epsilon,\qquad
c_t=\mathbb{1}\left[\exists k:\ D_{\mathrm{hard}}(p_k)<d_{\mathrm{safe}}\right],
```

其中 \(c_t\) 是硬障碍违反指示。实际实现不是解这个约束 MDP，而是**用 shield 把名义策略的动作投影到安全集**：

```math
\pi_{\mathrm{safe}}(A\mid o)=\mathrm{Proj}_{\mathcal{S}(o)}\big(\pi_\theta(A\mid o)\big),
```

\(\mathcal{S}(o)\) 由第 3 节的 CBF/速度/工作区约束定义。这样：

- 名义策略 \(\pi_\theta\) 仍是唯一学习模型；
- shield 是确定性的、无学习权重的约束层；
- 安全性与任务成功率解耦：shield 保证硬约束，任务成功率由名义策略 + 调度决定。

分析指标（不是官方分数）：

```math
S_{\mathrm{safe}}=\frac{1}{32}\sum_t\frac{1}{10}\sum_j y_{t,j}\cdot\mathbb{1}[\text{no safety violation}_{t,j}].
```

### 2.2 接口时间模型

设：

- \(f_c\)：evaluator 控制频率（Hz，未写死，必须实测）；
- \(H_c\)：提交的 `action_chunk_size`（本轮固定 5）；
- \(H_{\mathrm{eff}}\le H_c\)：内部有效执行前缀；
- \(\tau\)：网络 RTT + 推理 + 图像传输的等效延迟；
- \(\tau_{\mathrm{perc}}\)：双目/点云/动态簇的感知延迟；
- \(T_{\mathrm{react}}\)：从世界变化到控制约束生效的时间。

则：

```math
T_{\mathrm{react}}\approx \frac{H_{\mathrm{eff}}}{f_c}+\tau_{\mathrm{perc}}+\tau.
```

| 场景 | \(H_{\mathrm{eff}}\) | \(f_c\) | \(\tau_{\mathrm{perc}}\) | \(\tau\) | \(T_{\mathrm{react}}\) |
|---|---:|---:|---:|---:|---:|
| 官方 WLA 默认 | 30 | 30 | 50ms | 50ms | **1100ms** |
| CHUNK-SERVO 正常 | 5 | 30 | 50ms | 50ms | **267ms** |
| GUARD-SERVO 让行 | 1 | 30 | 50ms | 50ms | **133ms** |
| GUARD-SERVO 高延迟 | 1 | 30 | 50ms | 150ms | **233ms** |
| 低控制频率 | 3 | 10 | 50ms | 50ms | **400ms** |
| 低控制频率 + 让行 | 1 | 10 | 50ms | 50ms | **200ms** |

**推论**：

- 若实测 \(f_c=10\)Hz，5 步块是 500ms，不是 167ms；必须把 \(H_c\) 降到 3 或 2，或者接受更慢的反馈。
- 安全层的最坏反应时间必须用 \(T_{\mathrm{react}}\) 算，不能用 30Hz 的乐观值。
- 速度-分离约束 \(v_{\max}(D)=(D-d_{\mathrm{safe}})/T_{\mathrm{react}}\) 是安全层的核心；它随 \(T_{\mathrm{react}}\) 自动变保守。

### 2.3 安全场

定义 base 系点云 \(P_t=\{p_i\}_{i=1}^{N_t}\)，由头部双目反投影并变换到 base 系。将点云分为：

- 静态地图 \(P^{\mathrm{static}}_t\)：稳定超过 \(T_{\mathrm{static}}\) 的点（桌面、固定物体）；
- 动态簇 \(P^{\mathrm{dyn}}_t\)：与静态地图/机器人自运动不一致的残差点；
- 目标区域 \(\mathcal{T}_t\)：当前阶段要操作的物体/受器，由演示检索 + 局部重定位给出；
- 机器人自身 \(P^{\mathrm{self}}_t\)：URDF 在当前关节配置下的点云/胶囊。

硬障碍集合：

```math
\mathcal{O}_{\mathrm{hard}}(t)=\mathcal{O}_{\mathrm{dyn}}(t)\cup
\left(\mathcal{O}_{\mathrm{static}}^{\mathrm{tall}}(t)\setminus\mathcal{T}(t)\right)
\cup\mathcal{O}_{\mathrm{self}}(t)\cup\partial\mathcal{W},
```

其中 \(\mathcal{O}^{\mathrm{tall}}\) 是高于桌面阈值 \(\tau_h\) 的静态物体（防止撞倒旁边的杯子/试管），\(\partial\mathcal{W}\) 是工作区边界。

硬距离：

```math
D_{\mathrm{hard}}(p)=\min_{o\in\mathcal{O}_{\mathrm{hard}}}\|p-o\|.
```

软对象：

```math
\mathcal{O}_{\mathrm{soft}}(t)=\{\text{table plane}\}\cup\mathcal{T}(t)\cup
\mathcal{O}_{\mathrm{static}}^{\mathrm{low}}(t).
```

软约束不进入硬 CBF，而是：

```math
p_z\ge z_{\mathrm{table}}+h_{\min},\qquad
\|g_{t+1}-g_t\|\le\delta_g,\qquad
g_t\le g_{\max}(\hat w_{\mathrm{obj}}).
```

这样目标物可以被接触，桌面不会被压穿，夹爪不会无限闭合。

### 2.4 不确定性

**空间一致性**：同一观测 \(o_t\)，用扩散动作头采样 \(M\) 条 chunk：

```math
A^{(m)}_{0:H-1}\sim p_\theta(A\mid o_t),\qquad m=1,\dots,M.
```

定义两条 chunk 的归一化位姿距离：

```math
d_{\mathrm{pose}}(A^{(i)},A^{(j)})=
\frac{1}{H}\sum_{k=0}^{H-1}
\sqrt{
\frac{\|p^{(i)}_k-p^{(j)}_k\|^2}{\sigma_p^2}+
\frac{\|\log(R^{(i)\top}_kR^{(j)}_k)\|^2}{\sigma_r^2}
}.
```

空间不确定性：

```math
u^{\mathrm{spa}}_t=
\frac{2}{M(M-1)}\sum_{1\le i<j\le M}d_{\mathrm{pose}}(A^{(i)},A^{(j)}).
```

medoid 名义 plan：

```math
A^{\mathrm{med}}_t=\arg\min_{m}\sum_{j\ne m}d_{\mathrm{pose}}(A^{(m)},A^{(j)}).
```

**时间一致性**：相邻两次 plan 在重叠时间窗上比较。设旧 plan 在 \(t_0\) 生成，已执行 \(k\) 步；新 plan 在 \(t_1=t_0+k\) 生成。重叠段是旧 plan 的 \(k:H-1\) 与新 plan 的 \(0:H-1-k\)：

```math
u^{\mathrm{tmp}}_t=
\frac{1}{H-k}\sum_{j=0}^{H-k-1}
d_{\mathrm{pose}}\left(A^{\mathrm{old}}_{k+j},A^{\mathrm{new}}_{j}\right).
```

总不确定性：

```math
u_t=\max(u^{\mathrm{tmp}}_t,\ u^{\mathrm{spa}}_t)
```

默认只用 \(u^{\mathrm{tmp}}\)（零额外采样）；只有 GPU 有余量时才开 \(u^{\mathrm{spa}}\)。

**关键细节**：如果新旧 plan 之间发生了场景编辑（人进入/目标移动），\(u^{\mathrm{tmp}}\) 会自然变大，但这不是“策略犹豫”，而是“世界变了”。所以 DCM 必须用 SSF 的编辑信号做门控：场景编辑时重置旧 plan，不把这次差异计入不确定性。

### 2.5 可辨识性与启用条件

安全层只在以下条件满足时启用硬 CBF：

1. 头部双目 ROI 有效（视差有效像素 ≥70%，或动态簇点数 ≥ \(N_{\min}\)）；
2. 双目深度误差上界 \(e(Z)\le e_{\max}\)（见 4.1）；
3. 头相机外参/标定重投影误差 ≤5px；
4. 目标掩码置信度 ≥ \(\theta_{\mathcal{T}}\)；否则目标区域不排除，硬 CBF 只对人/自身/边界生效（更保守）；
5. 机器人 EE 位姿与图像时间戳偏差 ≤50ms；否则降速/停。

任一条不满足 → 回退：

```text
硬 CBF 可用 + 目标掩码可用：完整 GUARD-SERVO
硬 CBF 可用 + 目标掩码不可用：只对人/自身/边界硬约束；目标用软限速
硬 CBF 不可用：关闭硬 CBF；保留 v_max 全局限速 + 跟踪残差停 + 视觉伺服
```

## 3. 算法：GUARD-SERVO

### 3.1 符号表

| \(H_c\) | API chunk size | 5 步 |

### 3.2 总架构

```text
                    ┌─────────────────────────────────────────┐
                    │ Evaluator (N ports 8765..8765+N-1)      │
                    └──────────────────┬──────────────────────┘
                                       │ obs / action chunk
                                       ▼
                    ┌─────────────────────────────────────────┐
                    │ Per-port PolicyService (CPU)            │
                    │  ├─ CHUNK-SERVO: plan cache + servo     │
                    │  ├─ DCM: diffusion consistency          │
                    │  ├─ SSF: stereo -> safety field         │
                    │  ├─ CSR: certified shield + scheduler   │
                    │  └─ action adapter (WLA 54D -> API 21D) │
                    └──────────────────┬──────────────────────┘
                                       │ async, batched
                                       ▼
                    ┌─────────────────────────────────────────┐
                    │ Shared VLA server (GPU)                 │
                    │  UnifoLM-WLA-1.0, diffusion head, 30    │
                    └─────────────────────────────────────────┘
```

每个端口独立：

- 独立 `reset()`、plan cache、goal 状态、静态地图、动态簇跟踪、安全场；
- 共享 VLA server 只共享权重，不共享状态；用 session ID 区分端口；
- SSF/CSR 是 CPU 线程，不阻塞 websocket；VLA 异步请求，旧 plan + 伺服兜底。

### 3.3 主循环伪代码

```python
class GuardServoPolicy(ChunkServoPolicy):
    def get_action(self, obs):
        self._tick(obs)

        # ---------- 1. SSF: stereo safety field ----------
        cloud = self.ssf.stereo_to_cloud(
            obs.images.cam_left_high,
            obs.images.cam_right_high,
            self.calib,
            obs.state_d435,
        )
        cloud = self.ssf.transform_to_base(cloud, obs)
        self.ssf.update_static_map(cloud, obs)
        dyn = self.ssf.dynamic_clusters(cloud, obs)
        target = self.goal_retriever.target_region(obs, self.phase)
        D_hard = self.ssf.distance_to_hard(obs.ee_positions, dyn, target, obs)
        D_soft = self.ssf.distance_to_soft(obs.ee_positions, target, obs)

        # ---------- 2. DCM: diffusion consistency ----------
        self._maybe_request_plan(obs)          # async, non-blocking
        if self.plan is not None:
            u = self.dcm.update(
                new_plan=self.plan,
                old_plan=self.old_plan,
                executed=self.plan_idx,
                scene_edited=self.ssf.scene_edited,
            )
        else:
            u = 1.0                            # cold start: be cautious

        # ---------- 3. CHUNK-SERVO nominal chunk ----------
        if self.plan is None:
            self.plan = self.vla.predict(obs)  # cold start only
            self.plan_idx = 0
            u = 1.0

        a_ff = self.plan[self.plan_idx : self.plan_idx + self.H_c]
        e = self.servo.error(obs, self.goal, self.phase)
        a_nom = self.servo.compose(a_ff, e)    # absolute EE + gripper

        # ---------- 4. CSR: risk-adaptive scheduler ----------
        r_track = self.tracker.residual(obs, self.last_cmd)
        r = self.risk(u, D_hard, r_track, self.phase)
        H_eff, speed_scale, gain_scale = self.scheduler(r, self.phase)
        a_nom = self.scheduler.scale(a_nom, speed_scale, gain_scale)
        self.servo.set_gain_scale(gain_scale)

        # ---------- 5. CSR: certified shield ----------
        a_safe, feasible = self.shield.project_chunk(
            a_nom=a_nom,
            H_eff=H_eff,
            p0=obs.ee_positions,
            D_hard=D_hard,
            dt=1.0 / self.fc,
            alpha=self.alpha,
            d_safe=self.d_safe,
            v0=self.v0,
            T_react=self.T_react,
            self_dist=self.ssf.self_distance(obs),
        )

        # ---------- 6. yield / safe stop ----------
        if self.ssf.human_too_close(obs) or r >= self.r_stop:
            a_safe = self.shield.decelerate_and_hold(
                a_safe, obs, self.last_cmd, self.fc, self.a_max
            )
            self.state = "YIELD" if self.ssf.human_too_close(obs) else "SAFE_STOP"

        # ---------- 7. pad to fixed API chunk ----------
        a_api = self.shield.pad_hold(a_safe, self.H_c)
        self.last_cmd = a_api
        self.plan_idx += H_eff
        if self.plan_idx >= len(self.plan):
            self.plan = None
            self.plan_idx = 0

        return self.adapter.to_api(a_api, obs, self.token)
```

**规则**：

- VLA 永远不阻塞 `get_action`（除冷启动）；plan 过期就用旧 plan + 伺服。
- 每个 chunk 只做一次伺服；伺服失败不影响返回合法动作。
- 任何异常 → 返回上一组合法 chunk 或安全 hold；绝不返回 NaN/错误形状。
- `H_eff` 只影响内容，不改变 API 的 5 步长度；剩余步用减速/保持填充。

### 3.4 DCM：扩散一致性监视器

#### 3.4.1 时间一致性（默认）

```text
输入：旧 plan A_old（t0 生成，已执行 k 步），新 plan A_new（t1 生成）
输出：u_tmp ∈ [0,∞)

if k >= H - H_min_overlap:   # 重叠太少，跳过
    return None
if scene_edited:             # 人进入/目标移动，不是“犹豫”
    return None
overlap = A_old[k:H] vs A_new[0:H-k]
u_tmp = mean(d_pose(overlap))
return u_tmp
```

- \(H_{\min\mathrm{overlap}}=10\) 步；重叠太少时不估计。
- 场景编辑时重置，避免把“世界变了”误判为“策略犹豫”。
- 相位切换（抓取→搬运）时也重置，避免把合法的计划变化误判为不确定性。

#### 3.4.2 空间一致性（可选）

```text
输入：同一 obs 的 M 条扩散采样 A^(1..M)
输出：u_spa, medoid

if server.supports_multi_sample and gpu_headroom:
    samples = vla.sample(obs, M=4, share_vlm_embedding=True)
    u_spa = mean_pairwise_pose_distance(samples)
    medoid = argmin_m sum_j d_pose(A^m, A^j)
else:
    u_spa = None
    medoid = single_sample
```

- \(M=4\) 起步；若 p99 超预算，降到 2 或关闭。
- VLM embedding 只算一次，动作头批处理 M 次；否则开销不可接受。
- 若服务器不支持多采样，DCM 只用时间一致性；这是零成本的默认路径。

#### 3.4.3 归一化与校准

```math
\tilde u_t=\mathrm{clip}\left(\frac{u_t-u_0}{u_1-u_0},0,1\right).
```

- \(u_0,u_1\)：在验证集上校准。一个简单做法：取成功 episode 的 \(u\) 的 50% 分位数作为 \(u_0\)，95% 分位数作为 \(u_1\)。
- 门 S1：\(u\) 必须与动作误差/失败相关，AUROC ≥0.70；否则不用 DCM 做调度，退回固定谨慎速度。
- 不要用测试集校准；按 session/物体/背景分组划分。

### 3.5 SSF：双目安全场

#### 3.5.1 双目深度

对校正后的左右图，视差 \(d=u_L-u_R\)，深度：

```math
Z=\frac{f_x b}{d},\qquad
|\delta Z|\approx\frac{Z^2}{f_x b}|\delta d|.
```

- \(f_x\approx282.37\) px，\(b=0.0582526\) m；
- 下采样到 240×320 时，\(f_x'=141.2\) px，\(b\) 不变，视差范围按比例缩小；
- SGBM：视差范围 0–64 px（全分辨率）或 0–32 px（半分辨率），左右一致性检查，中值滤波，去小连通域；
- 反投影：\(P=Z K^{-1}[u,v,1]^\top\)，再用 \(T_{\text{base}\leftarrow\text{cam}}\) 变换到 base 系；
- 体素下采样 1cm；保留 ROI（桌面以上 0–1m，机器人前方 0.2–1.2m）。

**深度误差表**（\(\delta d=0.2\) px，全分辨率）：

| \(Z\) | 视差 \(d\) | \(|\delta Z|\) |
|---:|---:|---:|
| 0.3 m | 54.8 px | 1.1 mm |
| 0.5 m | 32.9 px | 3.0 mm |
| 0.8 m | 20.5 px | 7.8 mm |
| 1.0 m | 16.4 px | 12.2 mm |
| 1.5 m | 11.0 px | 27.4 mm |
| 2.0 m | 8.2 px | 48.7 mm |

**安全距离必须包含深度误差上界**：

```math
d_{\mathrm{safe}}(Z)=d_{\mathrm{margin}}+r_{\mathrm{gripper}}+e_{\mathrm{calib}}+
\frac{Z^2}{f_x b}\sigma_d.
```

在 0.5m 处，深度误差 3mm；在 1m 处，12mm。对于人手安全，取 \(d_{\mathrm{margin}}=3\)–5cm；对于旁边物体，取 1–2cm。

#### 3.5.2 静态地图与动态簇

```text
初始化：机器人静止 1s，累积点云到静态地图 M_static（1cm voxel）
每帧：
  cloud_base = transform(cloud, T_base_cam)
  residual = {p in cloud_base : dist(p, M_static) > tau_static}
  residual = residual - self_cloud(URDF, q_t)        # 去自运动
  clusters = EuclideanCluster(residual, tol=2cm, min_points=N_min)
  for each cluster:
      track velocity; if speed > v_move and in workspace:
          mark dynamic
      if static for T_static:
          merge into M_static; remove old points in the same region
```

- `tau_static`：2–3cm；大于双目深度误差，小于人手尺寸。
- 自运动剔除：URDF FK + 胶囊膨胀 5cm；时间戳同步；若点云与机器人本体重叠，优先认为是自身。
- 动态簇：不分类“人/物”，只要不是静态地图、不是机器人自身、在工作区内移动，就按“可能的人/障碍”处理。**安全优先，不追求语义**。
- 目标物被移动：旧静态点变成动态残差；人离开后，新位置稳定 \(T_{\mathrm{static}}\)，合并到静态地图；目标掩码随之更新。

#### 3.5.3 目标掩码

```text
从演示库检索当前任务/阶段的关键帧：
  T_base_target(k), T_target_ee*(k), I_wrist(k), bbox_target(k)
在线：
  用头双目 ROI + 局部 ICP/特征匹配，估计 T_base_target(t)
  如果置信度 >= theta_T：
      target_box = transform(bbox_target, T_base_target(t))
      从硬障碍集合中排除 target_box
  否则：
      target_box = none
      硬 CBF 只对人/自身/边界生效（更保守）
```

- 目标掩码是“允许接触”的许可证，不是“忽略目标”的许可证；目标附近的人手仍然是硬障碍。
- 透明/反光/变形目标：不建精确 3D box；用演示相对位姿 + 夹爪当前位置推断一个保守 box；置信度低就不排除，只做软限速。
- 多物体任务：当前阶段的活动物体集合由演示检索给出；非活动物体是软/硬障碍（高的硬、矮的软）。

#### 3.5.4 自身碰撞

```text
D_self = min distance between:
  - left EE sphere (r_grip)
  - right EE sphere (r_grip)
  - forearm capsules (from current q + IK of next EE target, if available)
if D_self < d_self:
  limit the step that reduces D_self
```

- 默认 \(d_{\mathrm{self}}=5\)cm；双手协同任务（如端盘/装箱）用阶段特定的 \(d_{\mathrm{self}}\)。
- 没有 IK 时，用当前肘部到 EE 的胶囊近似；有 IK 时用全臂胶囊。
- 自身碰撞是硬约束，但优先级低于人；如果人近，先让人。

### 3.6 CSR：CBF 安全盾

#### 3.6.1 Certified ball 投影

对每个执行步 \(k=1,\dots,H_{\mathrm{eff}}\)：

```math
h_k=D_{\mathrm{hard}}(p_{k-1})-d_{\mathrm{safe}},
\qquad
r_k=\alpha h_k,
```

```math
\Delta p_k^{\mathrm{nom}}=p_k^{\mathrm{nom}}-p_{k-1}^{\mathrm{safe}},
```

```math
\Delta p_k^{\mathrm{safe}}=
\begin{cases}
\Delta p_k^{\mathrm{nom}}, & \|\Delta p_k^{\mathrm{nom}}\|\le r_k,\\[4pt]
r_k\dfrac{\Delta p_k^{\mathrm{nom}}}{\|\Delta p_k^{\mathrm{nom}}\|}, & \text{否则}.
\end{cases}
```

再叠加速度-分离上限：

```math
v_{\max}(D)=\min\left(v_0,\frac{D-d_{\mathrm{safe}}}{T_{\mathrm{react}}}\right),
\qquad
\|\Delta p_k^{\mathrm{safe}}\|\le v_{\max}(D)\Delta t.
```

若 \(h_k\le0\)（已经进入安全距离内），则 \(r_k=0\)，本步保持；并触发 SAFE_STOP。

**方向性优化（可选）**：如果名义步主要是切向的，ball 投影会过度保守。可以用线性化 CBF：

```math
\nabla D(p_{k-1})^\top \Delta p_k\ge -\alpha h_k,
```

解一个小 QP；然后用真实距离回溯校验（backtracking），直到满足 \(h_k\ge(1-\alpha)h_{k-1}\)。若校验失败，回退 ball。默认用 ball（简单、可证明）；QP 只在仿真里验证有收益时启用。

#### 3.6.2 旋转与夹爪

- 旋转步长：\(\|\Delta\theta_k\|\le\omega_{\max}\Delta t\)；靠近硬障碍时按 \(r_k/\|\Delta p_k^{\mathrm{nom}}\|\) 同比例缩放。
- 夹爪：\(g_t\in[g_{\min},g_{\max}(\hat w_{\mathrm{obj}})]\)；\(|g_{t+1}-g_t|\le\delta_g\)。
- 夹持上限 \(\hat w_{\mathrm{obj}}\) 来自演示检索的物体宽度/任务类别；脆弱物体（试管、纸杯、注射器）用更低的上限。
- 没有力反馈：用“慢闭合 + 行程上限 + 跟踪残差/腕部视觉”代替力控；不声称能精确控制夹持力。

#### 3.6.3 安全停靠

当 \(r_t\ge r_{\mathrm{stop}}\)、人进入 \(d_{\mathrm{yield}}\)、或 \(h_k\le0\)：

```text
v_0 = 当前 EE 速度（由最近两帧观测估计）
a = a_max（标定值，保守取 0.5–1.0 m/s²）
for j = 1..H_eff:
    v_j = max(0, v_{j-1} - a*dt)
    p_j = p_{j-1} + v_j*dt
    if p_j violates shield: p_j = p_{j-1}; v_j = 0
剩余步：保持 p_j
```

停靠位移上界（连续时间）：

```math
d_{\mathrm{stop}}\le v_0\tau_{\mathrm{lat}}+\frac{v_0^2}{2a_{\max}}.
```

在 \(v_0=0.1\) m/s、\(\tau_{\mathrm{lat}}=0.1\)s、\(a_{\max}=1\) m/s² 时，\(d_{\mathrm{stop}}\le1.5\)cm；在 \(v_0=0.5\) m/s 时，\(d_{\mathrm{stop}}\le17.5\)cm。所以**人附近必须限速**，不能只靠停靠。

#### 3.6.4 固定 chunk 的填充

```text
a_safe 长度 <= H_c
pad 到 H_c：
  - 如果 a_safe 最后一步是运动：重复最后一步（hold）
  - 如果已经减速到 0：重复 hold
返回 H_c 步
```

- 评测端仍然执行 5 步，但后几步是保持；下一轮 `get_action` 会重新看世界。
- 这不是“提前打断 evaluator”，而是“在合法动作里提前停”。

### 3.7 风险自适应调度

```math
\tilde u=\mathrm{clip}\left(\frac{u-u_0}{u_1-u_0},0,1\right),
\quad
\tilde d=\mathrm{clip}\left(1-\frac{D_{\mathrm{dyn}}}{d_{\mathrm{warn}}},0,1\right),
\quad
\tilde e=\mathrm{clip}\left(\frac{r_{\mathrm{track}}-e_0}{e_1-e_0},0,1\right),
```

```math
r_t=1-(1-\tilde u)(1-\tilde d)(1-\tilde e).
```

- \(D_{\mathrm{dyn}}\)：到动态簇的最近距离；\(d_{\mathrm{warn}}\) 取 20–30cm。
- \(r_{\mathrm{track}}=\|p_{ee}^{\mathrm{obs}}-p_{ee}^{\mathrm{cmd}}\|\)：没有力传感器时的“被挡住/被抓住/滑移”代理。
- 在 CONTACT 阶段，\(\tilde e\) 的权重降低（接触本身会产生跟踪残差），\(\tilde d\) 的权重提高（人优先）。
- 在 TRANSIT 阶段，\(\tilde u\) 的权重提高（计划犹豫时减速观察）。

调度表：

| 风险 | 状态 | \(H_{\mathrm{eff}}\) | 速度 | 伺服增益 | 附加 |
|---|---|---:|---:|---:|---|
| \(r<0.3\) | NORMAL | 5 | 1.0 | 1.0 | 正常 |
| \(0.3\le r<0.6\) | CAUTIOUS | 3 | 0.6 | 0.7 | 更频繁重规划 |
| \(r\ge0.6\) | YIELD/SAFE_STOP | 1 | 0 | — | 停/让 |

**速度缩放**：对名义 EE 位移乘 \(s_t\)；不是对时间戳缩放。**增益缩放**：对伺服修正 \(\Delta\) 乘 \(g_t\)；不是对 VLA feedforward 乘。这样不会改变 VLA 的语义意图，只改变执行层的激进程度。

### 3.8 状态机

```text
INIT ──first obs──▶ PLAN ──plan ready──▶ SERVO
  ▲                   ▲                    │
  │                   │                    ├─ r>=r1 ──▶ CAUTIOUS
  │                   │                    │              │
  │                   │                    │              └─ r<r1 for K ──▶ SERVO
  │                   │                    │
  │                   │                    ├─ d_t<d_c ──▶ CONTACT
  │                   │                    │              │
  │                   │                    │              └─ contact released ──▶ SERVO
  │                   │                    │
  │                   └── replan ◀── RECOVER ◀── human leaves ──▶ YIELD
  │                                      │
  └──────────────────────────────────────┘
任意状态 ──task success / max steps / reset──▶ DONE
```

- `SERVO`：正常接近，PBVS 主导，IBVS 辅助。
- `CAUTIOUS`：不确定性/障碍接近；短前缀、低速、低增益。
- `CONTACT`：目标接触；法向缩幅、软约束、夹持行程上限。
- `YIELD`：人/动态簇进入 \(d_{\mathrm{yield}}\)；停、观察、不追人手。
- `SAFE_STOP`：硬约束不可行/跟踪残差异常；减速保持。
- `RECOVER`：人离开或场景编辑后；重定位目标、更新 goal、重规划。
- `DONE`：成功/超时；清理状态，等待 `reset()`。

### 3.9 动作适配

WLA 54D → 挑战赛 21D：

```text
WLA 54D:
  left_ee_rel[6], left_gripper[1], left_hand[6],
  right_ee_rel[6], right_gripper[1], right_hand[6],
  waist[3], torso[3], base_vxvy[2], base_wz[1],
  base_pose_rel[6], height[1], left_leg[6], right_leg[6]

挑战赛 ee 21D:
  left_ee_abs[6], right_ee_abs[6],
  left_gripper[1], right_gripper[1], pivot[7]
```

映射：

1. WLA 的每个未来动作是“相对 plan-time 当前 EE”的位姿；先把整个 30 步 compose 成 base 系绝对目标，再切片。**不能先切片再 compose**，否则第 6–30 步的锚点错误。
2. `left_ee_abs = compose(T_base_ee_left_current, exp(left_ee_rel))`；转 xyz+rpy。
3. `right_ee_abs` 同理。
4. gripper 直通，但加 \(g_{\max}(\hat w)\) 与 \(\delta_g\) 限制。
5. `pivot = [vx, vy, wz, yaw, pitch, roll, height]`，从 WLA base/waist 组合；具体符号/顺序必须用 `example_env.py` 和单任务通道验证。
6. 腿部/灵巧手在 `ee` 模式下不直接下发；`pivot` 若语义不匹配，先返回全零 pivot（保持下身体不动），只验证双臂。

**帧/TCP 风险**：WLA 的 EE 帧与挑战赛的 `*_ee_pose_gripper_base` 帧可能差一个 TCP/夹爪长度偏移；必须用 `example_env.py` 和真实数据做一次手眼/工具坐标校准（平移 ≤1cm、旋转 ≤2°）。这是 G6 的第一验证项。

## 4. 推导

### 4.1 双目深度误差

由 \(Z=f_x b/d\)：

```math
\frac{\partial Z}{\partial d}=-\frac{f_x b}{d^2}=-\frac{Z^2}{f_x b},
\qquad
|\delta Z|\approx\frac{Z^2}{f_x b}|\delta d|.
```

代入 \(f_x=282.37\)、\(b=0.0582526\)、\(|\delta d|=0.2\) px：

```math
|\delta Z|\approx 0.0609\,Z^2\ \text{m}\quad(Z\text{ in m}).
```

- \(Z=0.5\)：3.0mm；
- \(Z=1.0\)：12.2mm；
- \(Z=1.5\)：27.4mm。

**用途**：安全距离 \(d_{\mathrm{safe}}\) 必须加上 \(|\delta Z|\) 的上界；否则“看到 5cm”可能是“实际 3.8cm”。这也是为什么人附近要用 8–10cm 而不是 3cm。

### 4.2 离散 CBF 与 certified ball

距离函数 \(D(x)=\min_{o\in\mathcal{O}}\|x-o\|\) 是 1-Lipschitz：

```math
|D(x)-D(y)|\le\|x-y\|.
```

令 \(h_k=D(p_k)-d_{\mathrm{safe}}\)。若 \(h_k\ge0\)、\(\|\Delta p_k\|\le\alpha h_k\)，\(0<\alpha<1\)，则：

```math
h_{k+1}=D(p_k+\Delta p_k)-d_{\mathrm{safe}}
\ge D(p_k)-\|\Delta p_k\|-d_{\mathrm{safe}}
=h_k-\|\Delta p_k\|\ge(1-\alpha)h_k\ge0.
```

**推论**：球投影在每一步保证 \(h\) 以至少 \((1-\alpha)\) 的比例收缩，永不越过 \(d_{\mathrm{safe}}\)。这是充分条件，不是必要条件；方向性 QP 可以在保持安全的前提下减少保守性，但需要真实距离校验。

**透明性**：若名义步 \(\|\Delta p^{\mathrm{nom}}\|\le r\)，投影返回原步；所以自由空间里安全盾不改变动作。这正是“正常 trial 成本接近 0”的来源。

### 4.3 鲁棒裕度

设双目/标定/外参的合计距离估计误差上界为 \(e\)：

```math
|\hat D(p)-D(p)|\le e.
```

用膨胀安全距离 \(d_{\mathrm{safe}}'=d_{\mathrm{safe}}+e\)，定义 \(\hat h=\hat D-d_{\mathrm{safe}}'\)。若 \(\hat h\ge0\)，则：

```math
D\ge\hat D-e\ge d_{\mathrm{safe}}'-e=d_{\mathrm{safe}}.
```

所以 certified ball 用 \(\hat h\) 计算 \(r=\alpha\hat h\)，仍然对真实 \(D\) 安全。**代价**：人附近的安全距离更大，机器人更早停；这是必要的保守性。

### 4.4 安全停靠位移

连续时间、最大减速度 \(a_{\max}\)、感知+通信延迟 \(\tau_{\mathrm{lat}}\)：

```math
d_{\mathrm{stop}}\le v_0\tau_{\mathrm{lat}}+\frac{v_0^2}{2a_{\max}}.
```

若 \(v_0=0.1\) m/s、\(\tau_{\mathrm{lat}}=0.2\)s、\(a_{\max}=1\) m/s²：\(d_{\mathrm{stop}}\le2.5\)cm。若 \(v_0=0.5\) m/s：\(d_{\mathrm{stop}}\le22.5\)cm。**结论**：安全不是靠“停得快”，而是靠“人近时本来就慢”。速度-分离约束是主约束，停靠是最后一道。

### 4.5 不确定性校准

DCM 输出 \(u\) 不是概率，而是归一化距离。要把它当风险，需要校准：

- 在验证集上计算每个 plan 的 \(u\) 和实际执行误差/失败标签；
- 用 logistic 回归或等渗回归拟合 \(P(\text{failure}\mid u)\)；
- 门 S1：AUROC ≥0.70；否则 \(u\) 只用于“减速观察”，不用于“停”。

**注意**：\(u^{\mathrm{tmp}}\) 在场景编辑/相位切换时会自然变大；必须门控，否则会把“合法的计划变化”误判为“危险”。这是 DCM 最主要的假阳性来源。

### 4.6 延迟与稳定性（继承第 12 轮）

视觉伺服简化离散积分器：

```math
e_{k+1}=e_k-KH_c e_{k-d},\qquad d=\frac{\tau}{H_c/f_c}.
```

特征方程：

```math
z^{d+1}-z^d+KH_c=0.
```

- \(d=0\)：稳定域 \(0<KH_c<2\)；
- \(d=1\)：稳定域 \(0<KH_c<1\)；
- \(d=2\)：稳定域进一步缩小，必须降增益或加预测。

安全盾不改变这个稳定性分析；它只限制 \(\Delta\) 的幅度。若 \(T_{\mathrm{react}}>300\)ms，关闭 IBVS 高增益，只做 PBVS 粗对齐 + 限速。

## 5. 复杂度分析

设：

- \(N_p\)：下采样双目像素数（240×320 = 76,800）；
- \(D\)：视差范围（32–64）；
- \(N_c\)：下采样点云点数（5,000）；
- \(K\)：一次 `get_action` 中查询的 EE/路径点数（≤10）；
- \(M\)：扩散采样数（1–8）；
- \(H\)：VLA horizon（30）；
- \(H_c\)：API chunk（5）；
- \(C_{\mathrm{VLM}}\)：VLM 编码成本；
- \(C_{\mathrm{DiT}}\)：单条 chunk 的动作头去噪成本。

| 模块 | 复杂度 | 频率 | 估计延迟（CPU/GPU） |
|---|---|---|---|
| SGBM 双目 | \(O(N_pD)\) | 10–30Hz | 10–20ms（CPU，2 线程） |
| 点云变换/下采样 | \(O(N_p)\) | 10–30Hz | 2–5ms |
| KD-tree 构建 | \(O(N_c\log N_c)\) | 10–30Hz | 2–5ms |
| 动态簇 | \(O(N_c\log N_c)\) | 10–30Hz | 3–8ms |
| 距离查询 | \(O(K\log N_c)\) | 每次 get_action | <1ms |
| DCM 时间一致性 | \(O(H)\) | 每次新 plan | <1ms |
| DCM 空间一致性 | \(O(C_{\mathrm{VLM}}+MHC_{\mathrm{DiT}})\) | 每次新 plan | 1.2–2× 动作头 |
| 伺服 | \(O(1)\) | 每次 get_action | <1ms |
| CBF 投影 | \(O(H_c)\) | 每次 get_action | <1ms |
| 动作适配 | \(O(H_c)\) | 每次 get_action | <1ms |

**总安全开销**：

- 默认（时间 DCM，无多采样）：**15–30ms**/次，主要在双目；双目可以 10Hz 异步更新，5 步块 167ms 内复用，摊薄后 <5ms。
- 空间 DCM（M=4）：动作头约 2–4×，但 VLM 编码只一次；若动作头占端到端 20%，总延迟增加约 20–60%。需要实测；p99 超 150ms 就关。
- 内存：每端口点云/地图 <50MB；共享 VLA 6B bf16 约 12GB。
- GPU：安全层不用 GPU；DCM 多采样用同一 GPU，需与 N 端口共享；如果 N 大，默认关空间 DCM。

**结论**：安全层的 CPU 成本可控；真正的瓶颈是双目（可用 10Hz 异步）和空间 DCM（默认关）。这符合“每端口独立、CPU 轻量、不抢 GPU”的约束。

## 6. 正确性论证

### 命题 1（单步硬安全）

**条件**：距离函数精确、机器人能精确执行 \(\Delta p_k^{\mathrm{safe}}\)、\(h_k\ge0\)、\(\|\Delta p_k^{\mathrm{safe}}\|\le\alpha h_k\)。

**结论**：\(h_{k+1}\ge(1-\alpha)h_k\ge0\)。

**证明**：由 \(D\) 的 1-Lipschitz 性，

```math
D(p_k+\Delta p_k)\ge D(p_k)-\|\Delta p_k\|\ge D(p_k)-\alpha h_k.
```

两边减 \(d_{\mathrm{safe}}\)：

```math
h_{k+1}\ge h_k-\alpha h_k=(1-\alpha)h_k\ge0.
```

证毕。

### 命题 2（块内安全）

**条件**：每个执行步都满足命题 1；硬障碍集合在一个块内不新增（或新增被下一帧检测）。

**结论**：块内所有执行点的 \(h_k\ge0\)。

**证明**：对 \(k\) 归纳。\(h_0\ge0\)；若 \(h_k\ge0\)，由命题 1 得 \(h_{k+1}\ge0\)。证毕。

**注意**：如果人在块内突然进入，块内剩余步可能来不及反应；这就是为什么需要 \(H_{\mathrm{eff}}\) 小、速度-分离约束和 10–30Hz 感知。命题 2 的“硬障碍集合不变”是理想条件；实际用鲁棒裕度 \(e\) 和 \(T_{\mathrm{react}}\) 覆盖块内变化。

### 命题 3（鲁棒安全）

**条件**：\(|\hat D-D|\le e\)，用 \(d_{\mathrm{safe}}'=d_{\mathrm{safe}}+e\) 计算 \(\hat h\)，且 \(\|\Delta p\|\le\alpha\hat h\)。

**结论**：真实 \(h\ge0\)。

**证明**：

```math
h=D-d_{\mathrm{safe}}\ge\hat D-e-d_{\mathrm{safe}}
=\hat D-(d_{\mathrm{safe}}+e)=\hat h\ge0.
```

证毕。

### 命题 4（最小干预/透明性）

**条件**：名义步 \(\Delta p^{\mathrm{nom}}\) 在半径 \(r=\alpha h\) 的球内。

**结论**：投影返回 \(\Delta p^{\mathrm{nom}}\)，安全盾不改变动作。

**证明**：球是凸集，球内点的欧氏投影是自身。证毕。

**推论**：自由空间（\(h\) 大）中，安全盾对正常任务透明；只有在硬障碍附近才介入。这是“正常 trial 成本接近 0”的形式依据。

### 命题 5（球投影的最优性）

**条件**：需要把名义步投影到半径 \(r\) 的球内。

**结论**：径向缩放 \(\Delta p^{\mathrm{safe}}=r\Delta p^{\mathrm{nom}}/\|\Delta p^{\mathrm{nom}}\|\) 是欧氏距离最小的可行步。

**证明**：球外点到球的最近点在其径向；一阶条件/对称性。证毕。

### 命题 6（目标接触可行性）

**条件**：目标区域 \(\mathcal{T}\) 从硬障碍集合中排除；目标不在硬障碍的 \(d_{\mathrm{safe}}\) 膨胀区内。

**结论**：存在满足硬 CBF 的步，允许夹爪进入 \(\mathcal{T}\) 执行接触。

**证明**：硬约束只对 \(\mathcal{O}_{\mathrm{hard}}\setminus\mathcal{T}\) 生效；\(\mathcal{T}\) 内没有硬障碍，球半径 \(r=\alpha h\) 只受非目标障碍限制；只要目标与非目标障碍的距离大于 \(d_{\mathrm{safe}}\)，朝目标的步可行。证毕。

**注意**：如果目标紧贴硬障碍（例如杯子紧挨桌边/另一个高物体），硬 CBF 可能仍然限制进入；这时用软约束/阶段特定的 \(d_{\mathrm{safe}}\)，并在仿真里验证。不要为了“可证明”而把目标错误地排除。

### 命题 7（单模型合规）

**条件**：DCM 只对同一 VLA checkpoint 采样；SSF 用经典 SGBM/几何；CSR 是无学习权重的投影；演示检索用 ORB/颜色/几何（或同一 VLA encoder）。

**结论**：在线决策只有一个学习模型（VLA）；安全层是确定性约束，不是第二个策略。

**证明**：按定义，除 VLA 外没有可学习参数；SSF/CSR/DCM 的运算不含训练权重。证毕。

**注意**：这是“按我们的解释”合规；最终以官方规则解释为准。提交材料要写清楚；如果官方认为“多次采样”也算多模型，关闭空间 DCM，只保留时间 DCM（单次前向）和确定性 shield。

### 命题 8（安全停靠有界）

**条件**：最大减速度 \(a_{\max}\)、延迟 \(\tau_{\mathrm{lat}}\)、初速 \(v_0\)。

**结论**：停靠位移 \(d_{\mathrm{stop}}\le v_0\tau_{\mathrm{lat}}+v_0^2/(2a_{\max})\)。

**证明**：延迟期间匀速 \(v_0\tau_{\mathrm{lat}}\)；之后匀减速 \(v_0^2/(2a_{\max})\)。证毕。

**注意**：这是连续时间上界；离散执行/低层控制器可能有超调，所以 \(d_{\mathrm{safe}}\) 要留额外裕度。

### 命题 9（不确定性调度的安全性）

**条件**：DCM 输出任意（包括错误）；CSR 的硬约束不变。

**结论**：DCM 的错误不会破坏硬安全；它只影响速度/前缀/任务成功率。

**证明**：硬约束只依赖 \(D_{\mathrm{hard}}\)、\(d_{\mathrm{safe}}\)、\(\alpha\)、\(v_{\max}\)，不依赖 \(u\)；DCM 只进入 \(r_t\) 的速度/前缀调度。证毕。

**含义**：这是“两个正交安全层”的形式依据。即使 DCM 完全不可用，CBF 仍然工作；DCM 只影响“是否更早减速/让行”。

| 遮挡/透明 | 透明杯、试管、反光 | 深度空洞、误报、漏检 | S0/S2 |
| 延迟 | 0/50/100/150ms | 超调、停靠位移、碰撞 | S2 |
| 控制频率 | 10/30Hz | \(T_{\mathrm{react}}\)、成功率 | S2 |
| 消融 | CBF on/off；DCM on/off；硬/软分离；ball/QP | 成功率、干预率、碰撞 | S5 |

**仿真门 S2**：

- 500 次脚本化人手接近（0.1–0.5 m/s）零碰撞；
- 无人工况任务成功率下降 ≤5pp；
- 自由空间干预率 ≤10%；
- 人手进入后让行成功率 ≥95%，恢复后任务成功率 ≥70%；
- p99 延迟 ≤150ms（与真实 VLA server 联调时再测）。

**注意**：仿真人手是胶囊，真实人手有手指/衣物/反光；仿真只用于相对排序和稳定域，不用于预测真机绝对成功率。

### 7.3 真机单任务

| 项 | 设计 |
|---|---|
| 任务 | PlugInEthernet、HangCup、ZipUp、StackBowls、FoldTowel（与第 12 轮一致，便于对比） |
| 次数 | 每任务 5 次 A/B：GUARD-SERVO vs CHUNK-SERVO |
| 初始条件 | 同一位置/背景；尽量配对；随机化顺序 |
| 人为干扰 | 训练有素的操作员按固定协议介入（伸向目标/移动目标/阻挡），遵守官方安全规则 |
| 指标 | 成功、步骤分、耗时、碰撞、近碰、让行次数、干预率、p99 |
| 门 S3 | 零碰撞；成功率不降 >5pp；至少 2 个任务 human 轴 +10pp；FoldTowel 不回归 >5pp |

**统计**：

- 配对差值 \(\Delta_t=p_{\mathrm{on}}-p_{\mathrm{off}}\)；5 次/任务只能看方向，不能看显著性；
- 汇总 5 任务用 hierarchical bootstrap；报告 95% CI；
- 安全事件：25 次零碰撞的 95% 上界约 11%（rule of three），不能声称 <5%；要声称 <5%，需要约 60 次无碰撞；
- human 轴：每任务 2 次，单任务方差极大；聚合 5 任务 ×5 次 = 25 次 human 介入，仍只能看方向；正式结论要靠 32×10 全量或重复单任务通道。

### 7.4 全量干跑

| 项 | 设计 |
|---|---|
| 任务 | 32×10（或单任务通道的分批） |
| 端口 | N 个连续端口 8765..8765+N-1 |
| 指标 | 总平均成功率、步骤分、p99、timeout、内存、端口串扰 |
| 门 S4 | 无端口串扰；reset 干净；内存不涨；p99 ≤150ms；timeout 不升 |

**注意**：N 端口同时跑双目，CPU 可能成为瓶颈；每端口 2 线程 SGBM，N=8 时需要 16 核；若不够，降到 5–10Hz 或 160×120。不要为了安全层把 VLA 的 GPU 抢走。

### 7.5 消融

1. CBF on/off：安全 vs 成功率。
2. DCM on/off：恢复 vs 干预率。
3. 时间 DCM vs 空间 DCM vs 两者。
4. 硬/软障碍分离 vs 全硬 vs 全软。
5. ball vs 方向性 QP。
6. 目标掩码 on/off：接触任务成功率 vs 碰撞。
7. 速度-分离约束 on/off：停靠位移 vs 任务时间。
8. 安全停靠 vs 直接 hold：超调/碰撞。
9. 夹持行程上限 on/off：脆弱物体破损率 vs 抓取成功率。
10. WLA Base vs WLA 微调（安全层不变）。

### 7.6 门 S0–S5（汇总）

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| **S0** | 双目安全场是否可用？ | 0.3–1.0m 深度误差 ≤1cm；动态簇检测 ≤100ms；静态误报 ≤1%；API 图像与标定匹配 | 只做视场内粗安全场；关闭硬 CBF，保留限速 |
| **S1** | DCM 是否校准？ | AUROC ≥0.70；多采样开销 ≤1.5× 动作头 | 只用时间 DCM；或关闭 DCM，固定谨慎速度 |
| **S2** | 仿真安全盾是否有效？ | 500 次人手接近零碰撞；成功率降 ≤5pp；干预率 ≤10% | 降增益/缩硬障碍；只保留人-停 |
| **S3** | 真机是否不回归？ | 5 任务 ×5 A/B：零碰撞；成功率不降 >5pp；≥2 任务 human +10pp | 回退 CHUNK-SERVO + 全局限速 |
| **S4** | 延迟是否可接受？ | p99 ≤150ms；timeout 不升；N 端口无串扰 | 降双目频率/分辨率；关多采样 |
| **S5** | 消融是否支持因果？ | CBF on > off（安全）；DCM on > off（恢复）；硬/软分离 > 全硬 | 保留有效部分，砍掉无效部分 |

继承第 12 轮 G0–G7：腕部标定、演示检索、伺服收敛、真机涨点、编辑恢复、延迟、端口隔离、消融。S0–S5 是新增的安全门，不替代 G0–G7。

## 8. 竞赛策略

### 8.1 收益算术

- 总分 \(S=(1/32)\sum_t p_t\)。
- 人为干扰轴 = 2/10 = **20%**；若让行/恢复把 human 轴从 \(p_h\) 提到 \(p_h+\Delta_h\)，全局 \(+0.2\Delta_h\)。
  - \(\Delta_h=10\)pp → +2pp；
  - \(\Delta_h=20\)pp → +4pp。
- 接触任务若因限速/夹持上限减少 catastrophic failure：
  - 10 个 A 档任务各 +5pp → \(10/32\times5=+1.6\)pp；
  - 16 个任务各 +5pp → +2.5pp。
- 正常 trial 若安全盾透明：成本 ≈0；若过度保守：-2～-5pp。
- **现实预期 +1～+4pp**；不做 +10pp 承诺。

**统计噪声**：320 trials、\(p\approx0.25\) 时，\(\mathrm{SE}(S)\approx2.42\)pp；配对设计会低一些，但不要声称 +1–2pp 是结论。安全层的收益必须用配对 A/B + bootstrap CI 证明。

### 8.2 失败模式分诊

| 失败模式 | 典型任务 | GUARD-SERVO 该投什么 | 不该投什么 |
|---|---|---|---|
| 最后接触/插入/挂/叠/拉链/锁 | PlugInEthernet、HangCup、ZipUp、StackBowls、Unlock、ArrangeTestTubes、ToolboxStorage | 第 12 轮伺服 + 目标掩码 + 软接触约束 | 更大 VLA、更多语义数据 |
| 位置/人为干扰 | 5 类泛化轴；human_1/4 | 让行/重定位/恢复 + 硬 CBF + 跟踪残差 | 固定轨迹、开环 chunk、追人手 |
| 背景/干扰物/未见物品 | FruitSorting、ColorArrangement、OrganizeTools | VLA 数据增强/微调 + 局部 ROI + 软限速 | 纯几何伺服、语义分割网络 |
| 变形/语义/长程 | FoldTowel、PackBag、SpellRobot、ConveyorSorting | VLA 基座 + 任务数据 + 全局限速 | 6D 物体位姿网络、硬 CBF 对变形物 |
| 安全临界/易碎 | 试管、纸杯、注射器、药瓶 | SSF + 夹持行程上限 + 慢闭合 | 全力夹持、快速冲撞 |

### 8.3 任务组合（先验）

沿用第 12 轮 A/B/C 档，增加“安全临界”标记：

- **A 档：伺服 + 安全优先（19 个）**：T01 HangCup、T05 DisconnectEthernet、T09 ToolboxStorage、T10 PlugCharger、T12 Unlock、T13 ArrangeTestTubes、T14 OpenPillBottle、T17 OrganizeStationery、T18 PackBag、T19 ZipUp、T20 PaperCupStacking、T23 StoreRacket、T25 StackCups、T26 PlugInEthernet、T27 StackBowls、T28 StoreEarphones、T29 PackPhone、T31 OrganizePencilCase、T32 SyringeWaterTransfer。
- **B 档：VLA 优先（13 个）**：T02 FruitCollection、T03 PackDoll、T04 FruitSorting、T06 ColorArrangement、T07 PlacePhotoFrame、T08 OrganizeBookshelf、T11 PickOutBatteries、T15 OrganizeTools、T16 FoldTowel、T21 ArrangePlates、T22 SpellRobot、T24 ConveyorSorting、T30 RemovePinnedNote。
- **C 档：低投入/观察**：单任务通道里 \(p_t\) 接近 0 且失败在早期感知/抓取的任务；只保留全局限速，不投硬 CBF。

**安全临界子集（优先做 A/B）**：T09、T13、T14、T18、T19、T23、T27、T28、T29、T32；这些任务有高物体、易碎物、长距离搬运或注射器，安全失败代价高。

组合规则：

```text
priority_t = q_t * Δ_t * s_t / cost_t
```

- \(q_t\)：失败发生在最后 3 厘米/接触段的比例；
- \(\Delta_t\)：伺服 + 安全的条件增益；
- \(s_t\)：安全临界权重（人/易碎/高物体 = 1.2–1.5；纯搬运 = 1.0）；
- \(cost_t\)：工程/评测成本。

先做 A 档中 \(q_t\) 高、\(s_t\) 高、\(cost_t\) 低的 3–5 个任务；不要一次铺 19 个。

### 8.4 单任务通道协议（不计分，但决定是否烧正式提交）

1. 选 5 个代表任务：PlugInEthernet（插入）、HangCup（挂）、ZipUp（拉链）、StackBowls（叠）、FoldTowel（变形，防回归）。
2. 每任务 5 次 A/B：CHUNK-SERVO vs GUARD-SERVO；同一初始条件；随机顺序。
3. 人为干扰子实验：每任务 3–5 次脚本化介入（伸向目标/移动目标/阻挡），比较“无安全层 vs 有安全层”。
4. 通过标准：零碰撞；至少 3/5 任务成功率不降 >5pp；至少 2 个任务 human 轴 +10pp；FoldTowel 不回归 >5pp。
5. 再扫 \(H_c\in\{3,5,8\}\)、双目频率 10/15/30Hz、\(d_{\mathrm{safe}}\) 3/5/8cm；选 p99 和成功率的最佳折中。
6. 最后才跑 32×10 正式评测。

**统计诚实**：5 次/任务的 A/B 只能看方向；如果 CI 跨 0，继续测或放弃。不要用 +1–2pp 做结论。

### 8.5 预算与时间表

| 阶段 | 时间 | 交付 | 退出条件 |
|---|---:|---|---|
| P0 基线/接口 | 1 周 | WLA + API adapter；token/`pivot` 验证；chunk 30 基线 | 单任务通道 1 任务跑通 |
| P1 双目/安全场 | 1.5 周 | 双目标定；SGBM；静态/动态；目标掩码 | S0 |
| P2 CBF/调度 | 1.5 周 | certified ball；速度-分离；安全停靠；状态机 | S2（仿真） |
| P3 DCM | 1 周 | 时间一致性；可选空间一致性；校准 | S1 |
| P4 集成/单任务 | 1.5 周 | GUARD-SERVO 集成；5 任务 A/B | S3/S4 |
| P5 全量干跑 | 1 周 | 32×10 干跑；N 端口；p99/内存 | S4 |
| P6 提交 | 1 周 | 提交包、合规说明、回滚开关 | S5 + 全部门 |

**算力**：

- 1×24GB GPU：WLA Base 微调/单端口推理；
- 1×40GB/80GB GPU（可选）：多端口共享 VLA server/批处理；
- 16–32 CPU 核：双目/安全场/检索/回放；N 端口每端口 2 线程。

**人员**：

- 1 人：双目/几何/安全场；
- 1 人：WLA 微调/推理/部署；
- 1 人：评测/统计/竞赛策略；
- 可兼职；总计 8–9 周。

### 8.6 提交节奏

1. **W0**：官方 WLA + API adapter + chunk 30 基线；单任务通道跑 1 个任务，确认接口/`pivot`/token/控制频率。
2. **W1**：安全基线（CHUNK-SERVO + 全局限速 + 跟踪残差停）先锁 tie-break（若允许多次提交）。
3. **W2–W4**：SSF/CSR/DCM；仿真 S0/S1/S2；单任务 A/B。
4. **W5**：chunk/双目频率/安全距离扫描；全量干跑。
5. **W6**：最终提交；保留回滚开关。

若只允许一次提交：跳过 W1 的安全基线，W5 后再交；不要用正式 320 trials 做未验证的 A/B。

## 9. 风险与合规

### 9.1 单模型合规的四种模式

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | GEO-RESIDUAL 只离线生成相位/接触标签；线上只有 VLA | 最低 | 保守首选 |
| C2 确定性控制器 | 伺服 + CBF shield + 速度限制；无学习权重 | 低；需向官方说明 | **主推** |
| C3 同 checkpoint 采样/特征 | DCM 用同一 VLA 的扩散采样；目标描述子用同一 encoder | 低–中；需说明“不是第二个模型” | 默认时间 DCM；空间 DCM 可选 |
| C4 同 checkpoint 微调 | 用数字孪生生成安全数据，微调同一 action head 的安全损失 | 中；需证明仍是同一模型 | 可选，不作为核心 |

禁止：加载第二个学习策略/残差网络/独立语义分割网络做在线决策。

### 9.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 安全层过度保守 | 正常 trial 成功率下降 | certified ball 只在硬障碍附近介入；目标掩码；阶段化安全距离；S2/S3 A/B |
| 双目深度失败（透明/反光/无纹理） | 安全场空洞/误报 | 只对人/自身/边界硬约束；目标用软限速；深度误差膨胀；跟踪残差停 |
| 动态簇误报（自身/反光） | 机器人冻结/让行过多 | URDF 自剔除 + 时间同步 + 运动一致性；模糊时减速而非急停 |
| 人头/手在 FOV 外 | 看不到人，撞上去 | 不承诺 360°；全局限速；工作区边界；若未来有 LiDAR 则接入 |
| 无力/触觉 | 捏碎/压坏物体 | 夹持行程上限 + 慢闭合 + 物体宽度表 + 腕部视觉/跟踪残差 |
| 头部双目标定与 API 图像不匹配 | 深度系统偏差 | S0 第一项；现场棋盘格标定；必要时只用单目+桌面平面粗安全 |
| 控制频率不是 30Hz | 5 步块变长，反应变慢 | P0 实测；按 \(f_c\) 选 \(H_c\)；低 \(f_c\) 用 \(H_c=2/3\) |
| RTT 高 | 安全层反应慢 | 本地安全盾不依赖网络；VLA 异步；plan 过期用旧 plan + 限速 |
| 空间 DCM 开销大 | p99 超预算 | 默认时间 DCM；空间 DCM 只在 GPU 有余量时开 |
| 单模型解释 | 被判定为第二个模型 | C2/C3；同一 checkpoint；确定性 shield；提交材料写清；可关空间 DCM |
| EE 抽象/低层控制器超调 | 实际轨迹越界 | 保守 \(d_{\mathrm{safe}}\)；速度-分离；仿真标定 \(a_{\max}\)/延迟；真机小步验证 |
| 目标掩码错误 | 挡住目标或放行危险接触 | 演示检索 + 局部重定位；置信度低不排除；人优先 |
| 人拿走目标 | 任务失败/超时 | 让行 + 重定位；\(T_{\mathrm{wait}}\) 后优雅失败；不追人手 |
| 让行超时 | 180s 限制 | 总让行时间上限 20s；人持续阻挡则 fail fast |
| 评测噪声 | 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |
| 数据泄漏 | 目标检索离线指标虚高 | 按 session/物体/背景分组；相邻帧不跨 split |
| `pivot` 语义不一致 | 动作被拒/机器人不动 | `example_env.py`/单任务通道验证；零 pivot 回退 |
| 提交次数限制 | 无法多次 A/B | 邮件确认；单任务通道先验证；一次提交则保守 |

### 9.3 已知风险与未解决

- 最大的风险不是“安全盾不够安全”，而是**安全盾在 80% 的正常 trial 上过度保守**；S2/S3 的“成功率不降 >5pp”是硬门。
- 双目安全场的 FOV/盲区/透明物体是物理限制；本轮只承诺视场内 + 限速，不承诺 360°。
- 没有力/触觉，夹持安全只能靠行程/速度/视觉，不能保证不捏碎所有物体。
- 头部双目与 API 图像的对应关系（IR vs RGB）未核实；S0 必须先过。
- 控制频率、RTT、人为干扰协议未实测；本报告的公式保留符号，不把 30Hz 当事实。
- 官方是否允许多次提交、是否允许单任务通道做人为干扰，未确认。
- 空间 DCM 是否被官方视为“多次模型调用”，未确认；默认时间 DCM 规避。
- 仿真人手是胶囊，真实人手有手指/衣物/反光；仿真只用于相对排序。
- 全量 32×10 下，N 端口双目 CPU 可能成为瓶颈；需要压测。
- 安全层不直接提高官方分数；它通过减少失败/恢复人来间接提高成功率。不要把“安全”当成分数承诺。

## 11. 一句话押注

**用同一个扩散动作头的采样一致性估计“它有多犹豫”，用头部双目构造“窄基线虚拟 LiDAR”的米制安全场，用确定性的 certified ball + 速度-分离 + 让行/重定位把每个 5 步块投影到安全集——在不新增学习模型、不改变 API chunk size、不假设 LiDAR/力/触觉的前提下，让 CHUNK-SERVO 在人的旁边既敢动、又知道什么时候不该动。**
