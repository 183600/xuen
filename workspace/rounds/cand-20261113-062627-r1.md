# 第 1 轮（灵感循环 v3：「模型量化」×「视觉编码器」）—— 把精度与注意力变成闭环控制的可调预算

> 承接 research.md 已沉淀的 UniBot 事实与 UIP v2 清单。v2 的旗舰是「扰动撤回检测-重做」。本轮不推翻它，而是补上此前被当作工程细节的一层：在单卡、多端口、4 路相机、开环动作块的真实约束下，**精度（量化）与视觉 token（编码器）共同决定「能否每 k 步重观测」**。因此量化与视觉编码器不是部署杂项，而是策略级变量。

## 0. 直觉解释（先讲人话）

### 0.1 模型量化

直觉：量化不是「把模型压小」这么简单，而是**给不同模块分配不同的小数位数**。就像乐队排练：视觉编码器人数最多、对噪声相对不敏感，可以「少排」；动作头是独奏，少排一个音就露馅。真正的研究问题不是「能不能 INT8」，而是**「哪些位可以省、省下来的延迟拿去换什么」**。

### 0.2 视觉编码器

直觉：视觉编码器不是「越大越好」，而是**「看哪里、看多细」的预算问题**。4 路 480×640 每步全分辨率重算，等于为整张桌子付钱；而任务往往只关心夹爪和目标物体周围的一小块。量化与 token 剪枝/缓存/ROI 放大，本质是同一个「视觉比特预算」的四个旋钮。

### 0.3 两者相乘：量化购买反应性

直觉：量化省下延迟 → 可以更频繁重观测（更小 k）→ 更能发现「人为撤回」并重做。**量化不是效率优化，而是把「反应性」从工程约束变成可购买的商品。** 这直接把本轮与 v2 的旗舰（UIP-01′/09′）焊在一起。

## 1. 严谨定义（本轮新增）

**定义 1（策略分解）**：π = H_act ∘ B ∘ E_vis ∘ E_lang。E_vis 处理 4 路相机，E_lang 编码任务语言 l，B 为共享骨干，H_act 输出动作块 A=(a_1..a_{T_a})。

**定义 2（精度分配）**：p: M → {FP16, FP8, INT8, INT4}，M 为可量化模块集合。p 在提交时固定，运行期不切换（避免 metadata 握手后不可变带来的接口风险）。

**定义 3（成本）**：C(p) = (L(p), M(p), E(p))，分别为端到端延迟、显存、能耗；在给定并发端口数 N 与声明块长 k 下测量。延迟必须同时看 p50 与 p95——榜单可信度看的是「逐步延迟及其波动」。

**定义 4（分轴量化风险）**：
R_axis(p) = E_{τ~D_axis}[ score_FP16(τ) − score_p(τ) ]，
其中 axis ∈ {未见物体, 人为干扰, 位置, 干扰物, 背景}，score = 成功率 + 步骤分（沿用赛事口径）。要求**每条轴的 R_axis 都不超阈值**，而不是只看平均值。

**定义 5（量化敏感度）**：S_m = E_{o~D_cal}[ d(π_ref(o), π_{m←b}(o)) ]，d 为动作空间距离（关节/末端位姿的加权 L2），并辅以任务级 Δscore。可理解为「把模块 m 降到 b 位后，动作分布被推离参考分布多远」。

**定义 6（视觉比特预算）**：B_frame = Σ_{c∈C} N_c · b_c · 1[未命中缓存]，C 为 4 路相机，N_c 为每路 token 数，b_c 为每 token 的比特数。预算的「信息侧」目标是最大化控制相关互信息 I(Z; A* | l)，其中 A* 为专家动作；工程代理可用「动作重构误差」或「步骤分代理」估计。

**定义 7（任务条件 foveation）**：把每帧划分为 ROI 区域 R（目标物体 + 夹爪 + 接触点）与背景 G。分配 N_R ≫ N_G、b_R ≥ b_G、分辨率 r_R > r_G；ROI 由语言 + 末端在图像上的投影 + 主骨干的交叉注意力共同给出。

**定义 8（缓存失效事件）**：e_t = 1[ D(o_t^{G}, o_{t−1}^{G}) > δ ]，D 为低成本的帧差/特征差。e_t=1 时重算背景 token，并**同时触发一次进度核验**——因为「画面显著变化」既是缓存失效信号，也是「人为撤回」的候选信号。

**定义 9（闭环量化稳定性）**：在闭环 rollout 中，量化策略的动作抖动 J = E‖a_t − a_{t−1}‖ 与重做率 ρ_redo 不得显著高于 FP16 基线；否则即使单步误差小，也会在接触密集步（插网线/合盖/拉链）累积失败。

## 2. 事实底座与工作假设

### 2.1 已核实事实（继承，检索日期 2026-11-12）

- 任务集为官网新 32 任务（T01–T32），每任务计分点合计 100 分；末步分值恒 ≥ 前序步。
- 计分 = 平均成功率 + 步骤分；排行榜仍 Coming Soon，无法取得「榜首 <30%」的证据。
- 接口为开环动作块：`get_action(obs)` 返回 `action_chunk_size` 步，评测端整块执行后才再次调用；`reset()` 每 episode 一次；`metadata` 在握手时决定控制空间/obs 选择/图像缩放/块长。
- 图像经 JPEG q95、4:4:4 上线；`obs_delta_indices` 决定发送哪些键与时间堆叠几帧，堆叠越多 = 越多张 JPEG = 越高延迟/带宽。
- 数据侧为 4 路 AV1 480×640（head_stereo_left/right、wrist_left/right）+ 丰富 state/action；接口只收发其子集（4 图≈head+wrist；动作含 pivot[7]）。
- 泛化字段实测只有 `unseen_object_*` 与 `human_*` 两类前缀；`human_*` 大量是「把已完成进度撤回」。
- 单模型多任务合规；外部 VLM 验证器有被判「非单模型」的风险（v2 已记录）。

### 2.2 本轮工作假设（未核实，需手册或实测）

- **A1（资源瓶颈）**：推理卡显存/延迟是实际硬约束。手册未公开具体 GPU、评测轮次、时限与控制频率，本轮把「延迟/显存」当约束做保守设计。
- **A2（合规）**：同一骨干的量化版本仍算「单模型」；但「外部检测器/外部 VLM」可能不算。所有视觉 ROI/验证逻辑优先内化到主骨干。
- **A3（敏感度异质）**：动作头与最后融合层对量化最敏感；视觉编码器相对鲁棒；腕部相机比头部相机更敏感。**这是本轮最需要实验证伪的假设。**
- **A4（接口刚性）**：若评测端强制返回恰好 `action_chunk_size` 步，则运行期不能改变 k；量化收益只能用于「投机预计算 / 更多端口 / 更高重观测频率的提交配置」，不能在同一次提交内动态变 k。
- **A5（缓存可行）**：固定底座的桌面任务中，头部相机背景大体静态；腕部相机随臂运动，缓存收益较小、失效更频繁。

## 3. 两个灵感词的解读

### 3.1 模型量化：三个层次

1. **部署级**：PTQ、混合精度、算子融合。收益直接（显存/延迟），风险是离群值与分布偏移。
2. **训练级**：QAT、量化感知蒸馏。用训练把量化噪声「预演」进策略，重点不是特征 MSE，而是**动作一致性与时序一致性**。
3. **系统级（本轮主张的研究点）**：量化换来的延迟预算再投资——更小 k、更多并发端口、更强视觉前端。**只做第 1 层是工程，做第 3 层才是研究。**

### 3.2 视觉编码器：四个旋钮

| 旋钮 | 做法 | 省什么 | 主要风险 |
|---|---|---|---|
| 空间 | ROI 裁剪 + 高分辨率 fovea | token 数、像素数 | ROI 漏掉目标/干扰物 |
| token | 剪枝、合并、时序缓存 | 注意力计算 | 细微接触变化被丢掉 |
| 视角 | 腕部高精度、头部低精度 | 编码器算力 | 全局场景理解变弱 |
| 精度 | 编码器 INT8/FP8，动作头 FP16 | 显存、带宽 | 未见物体上的激活离群 |

### 3.3 交叉点：量化 → 反应性预算

设 FP16 下每步推理延迟 L16，量化后 L_q < L16。若评测允许选择更小 k，则每 episode 的重观测次数从 T/L16 提升到 T/L_q；在「人为撤回」发生的任务里，发现撤回的平均延迟下降，步骤分期望上升。**量化因此不是「降本」，而是「用算力换反应性」的交换率。**

## 4. 瓶颈假设 H1–H5

- **H1（异方差量化误差）**：量化误差在泛化轴上是异方差的；干净背景上几乎无损，未见物体/背景上误差放大。⇒ 必须做「分轴校准 + 分轴验收」。
- **H2（非对称精度）**：动作头/最后融合层最敏感，视觉编码器最鲁棒。⇒ 保持动作头 FP16，把量化压力集中到视觉塔与骨干，是性价比最高的保险。
- **H3（视觉边际价值不均）**：ROI 内 token 的边际价值远高于背景 token。⇒ foveation 能在步骤分不降的前提下显著降延迟。
- **H4（量化→反应性）**：量化省下的延迟若换成更小 k，可提升对「反向撤回」干扰的恢复；但若接口强制固定 k，则收益转为「投机预计算 + 多端口吞吐」。
- **H5（共享骨干的尾延迟）**：多端口共享量化骨干能提升吞吐，但批处理会抬高 p95 延迟；需要确定性批调度与每端口状态隔离，否则伤可信度。

## 5. 候选发散 → 合并为 v3 清单

围绕两词发散 9 个草案：

1. 全模型 INT8 一刀切（否决：动作头风险高）。
2. 视觉塔 INT8 + 动作头 FP16 的非对称精度（保留 → **UIP-16 ASQ**）。
3. 用泛化五轴做校准集分层（保留 → **UIP-17 GAC**）。
4. 语言/夹爪引导的 ROI foveation（保留 → **UIP-18 TCFQ**）。
5. 腕部/头部差异化精度（保留 → **UIP-19 VPG**，可并入 16/18）。
6. 量化省延迟换更小 k（保留 → **UIP-20 QCL**）。
7. 用逐层量化敏感度反推「哪些视觉特征对计分步重要」（保留 → **UIP-21 QSD**，研究工具）。
8. 训练时注入量化噪声做数据增强（并入 UIP-16 的 QAT 选项）。
9. 外部轻量检测器做 ROI（否决：单模型合规风险，优先用主骨干交叉注意力）。

合并后得到 6 个新增项（UIP-16~21），并与 v2 的 UIP-01′/08′/09′/11/13/14 建立接口。旗舰定为 **UIP-16 ASQ**，次旗舰为 **UIP-18 TCFQ**。

## 6. 与 v2 旗舰的耦合

- **UIP-01′（滚动验证-重做）**：量化降低每步推理成本，使「每 k 步核验 + 撤回重做」在延迟上可行；缓存失效事件 e_t 可直接复用为「候选撤回」触发器。
- **UIP-09′（扰动撤回检测）**：背景/目标突变既是缓存失效信号，也是撤回信号；两者共享一个廉价变化检测器，避免重复计算。
- **UIP-13 ACS（自适应块长）**：加入「精度感知」——高精度模式用于接触密集步，低精度模式用于远距离搬运。
- **UIP-08′ LAT-ENG**：量化是降低每端口成本的第四根支柱（前三根是共享骨干、批处理、状态隔离）。
- **UIP-14 MSGR**：冻结的量化基础视觉编码器 + 每技能轻量适配器，兼顾泛化、显存与单模型合规。
- **UIP-11/12 GSO/DRF**：量化后的策略 rollout 更快，可扩大离线搜索/数据生成的吞吐；但**判分仍以 FP16 代理为准**，避免「量化模型自己给自己打分」。

## 7. 本轮最大风险

**一句话**：量化误差在未见物体/背景上是分布偏移的，干净验证集上几乎无损的 INT8 模型可能恰好在计分的那几条泛化轴上崩掉，而榜单尚未开放、无法及时校准——因此必须把「分轴量化风险」当作一等公民，并保留可回退的 FP16 动作头与真机锚点。

## 1. 旗舰深潜：UIP-16 · ASQ（Asymmetric Sensitivity-aware Quantization）

### 1.1 机制

- **非对称精度**：动作头 H_act 与最后融合层保持 **FP16**；共享骨干 B 用 **FP8/INT8**；视觉编码器 E_vis 用 **INT8**（腕部分支可保 FP8）。理由：动作头参数量小、对精度最敏感；视觉塔参数量大、对量化噪声相对鲁棒。
- **敏感度驱动分配**：离线在分轴校准集上逐模块做「降位扰动」，估计 S_m（动作分布偏移）与 Δscore；按「每毫秒延迟节省的风险」从低到高逐模块降位，直到触达分轴风险上限或延迟目标。
- **训练级补偿**：优先 QAT + 量化感知蒸馏，损失 = 动作 L1/L2 + 时序一致性（相邻步动作差分）+ 特征对齐；**不只做特征 MSE**，因为闭环关心的是动作分布。
- **可回退**：推理期若验证器置信度低（接触密集步/未见物体），可对 ROI 分支临时启用更高精度（仅在模型内部，不改接口 metadata）。

### 1.2 与 v2 差异

v2 的 LAT-ENG 只做「共享骨干 + 批处理 + 端口隔离」；ASQ 把**位宽**变成可优化维度，并且明确「动作头不量化」这条红线。v2 的 MSGR 只讲模块化路由；ASQ 把「视觉基础模型冻结 + 量化」作为模块化的底座。

### 1.3 可行性

- 高。PTQ（SmoothQuant/AWQ 类离群值处理 + per-channel scale）可在单卡完成；QAT 成本较高，作为可选第二阶段。
- 不改变接口：量化只发生在服务端推理；`observation`/`action` 的 dtype/shape 仍按 README。

### 1.4 资源

- 1 张推理卡做 PTQ 校准与延迟压测；公开 32 数据集抽帧做校准；无需真机即可完成大部分实验（真机只做锚点）。

### 1.5 落地步骤

1. 建立 FP16 参考策略与分轴校准集（UIP-17）。
2. 逐模块敏感度剖面（UIP-21）：视觉塔、骨干、融合层、动作头、语言塔分层。
3. 用背包/贪心分配位宽，得到若干候选配置（保守/均衡/激进）。
4. PTQ 校准（离群值处理）→ 闭环回放评估 → QAT 微调（可选）。
5. 延迟/显存/动作抖动压测（多端口）→ 选配置。
6. 真机锚点校准，锁定提交配置。

### 1.6 风险

- 动作头若被误量化，接触密集步会抖动 → **硬约束：动作头 FP16**。
- 注意力/归一化层对位宽敏感 → 默认保 FP16，只量化线性层。
- 校准集若只含干净背景，风险被低估 → 由 UIP-17 兜底。

## 2. 严谨形式化：精度分配的受限优化

### 2.1 优化目标

$$
\min_{p}\; L(p)\quad \text{s.t.}\quad M(p)\le M_{\max},\quad R_{\text{axis}}(p)\le \varepsilon_{\text{axis}}\;\; \forall\,\text{axis}.
$$

等价的拉格朗日形式（便于网格搜索）：

$$
\max_{p}\; \widehat{\text{score}}(p)-\lambda_L L(p)-\lambda_M M(p)-\sum_{\text{axis}}\lambda_{\text{axis}}\max(0,R_{\text{axis}}(p)-\varepsilon_{\text{axis}}).
$$

其中 $\widehat{\text{score}}$ 用离线计分神谕（v2 的 UIP-11 GSO）或真机小样本估计。

### 2.2 敏感度的可计算近似

对模块 $m$ 从参考位宽 $b_0$ 降到 $b$：

$$
S_m(b)=\mathbb{E}_{o\sim D_{\text{cal}}}\Big[\big\|\pi_{b_0}(o)-\pi_{m\leftarrow b}(o)\big\|_W^2\Big],
$$

$W$ 为动作维度权重（末端位置 > 姿态 > 夹爪 > 冗余关节）。任务级版本：

$$
\Delta\text{score}_m(b)=\mathbb{E}_{\tau\sim D_{\text{cal}}}\big[\text{score}_{b_0}(\tau)-\text{score}_{m\leftarrow b}(\tau)\big].
$$

### 2.3 位宽分配的贪心规则

按「单位延迟节省的风险」排序：

$$
\text{priority}_m(b)=\frac{\Delta L_m(b)}{\max(\Delta\text{score}_m(b),\epsilon)}.
$$

优先降位 priority 最小者；每次降位后重估分轴风险，触顶即停。若需全局最优，可把小规模候选做成 0-1 背包（每模块 2–3 个档位）。

### 2.4 视觉比特预算

$$
B_{\text{frame}}=\sum_{c\in C} N_c\, b_c\,\mathbf{1}[\text{未命中缓存}],\qquad
\max_{\{N_c,b_c\}}\; I(Z;A^*\mid l)-\lambda B_{\text{frame}}.
$$

直接估互信息困难，工程代理：

$$
\mathcal{L}_{\text{proxy}}=\big\|\hat{a}(Z)-a^*\big\|_1+\beta\big\|\hat{a}(Z_t)-\hat{a}(Z_{t-1})\big\|_1,
$$

第二项保证时序一致性（避免 token 抖动导致动作抖动）。

### 2.5 Foveation 的分配

ROI 内 token 数 $N_R$、背景 $N_G$，满足 $N_R+N_G=N_{\max}$。给定 ROI 面积占比 $\alpha$：

$$
N_R=\min\!\big(N_{\max},\,\lceil \alpha N_{\max}/\gamma\big\rceil),\qquad N_G=N_{\max}-N_R,
$$

$\gamma$ 为「fovea 放大倍数」。背景下采样到 $1/s$ 分辨率，token 数约降为 $1/s^2$。

## 3. 视觉编码器的四个旋钮（工程对照表）

| 旋钮 | 具体做法 | 预期收益 | 主要风险 | 与接口的关系 |
|---|---|---|---|---|
| 空间 ROI | 语言+夹爪投影+交叉注意力选 ROI，高分辨率编码 | token −40%~70% | ROI 漏掉干扰物/目标 | metadata 的 image_resize 握手后不变；ROI 在**服务端内部**做，不请求改分辨率 |
| token 剪枝/合并 | 保留 CLS + ROI patch + 稀疏背景 patch；相邻 token 合并 | 注意力算力 −30%~60% | 细微接触变化丢失 | 纯模型内 |
| 时序缓存 | 背景 token 命中则复用；$e_t$ 触发重算 | 静态场景延迟 −20%~50% | 快动作/遮挡导致误复用 | 纯模型内；需按端口隔离缓存 |
| 视角分级 | 腕部 FP8/高分辨率，头部 INT8/低分辨率 | 显存 −30% 左右 | 全局场景/大范围移动变弱 | 纯模型内 |
| 精度分级 | 视觉塔 INT8，动作头 FP16 | 延迟/显存显著下降 | 未见物体离群值 | 纯模型内 |

**注意（接口红线）**：`image_resize` 由 metadata 在握手时决定，运行期不能改；因此「省像素」只能靠**服务端内部裁剪/下采样**，不能指望评测端少发像素。`obs_delta_indices` 也应在握手时一次性声明，运行期不动态改。

def build_axis_balanced_calib(dataset, axes, n_per_cell=64, seed=0):
    # axes = {unseen_object, human, position, distractor, background}

        calib[axis] = stratified_sample(pool, n_per_cell, seed)

### 4.2 敏感度剖面与位宽分配（UIP-16 + UIP-21）

```python
def profile_and_assign(model_fp16, calib, modules, bits=(8, 4),
                       latency_budget_ms=200, axis_eps=2.0):
    base = evaluate_closed_loop(model_fp16, calib)      # score + p50/p95
    table = {}
    for m in modules:
        for b in bits:
            q = quantize_only(model_fp16, m, b)         # 只降该模块
            ev = evaluate_closed_loop(q, calib)
            table[(m, b)] = {
                "dscore": {ax: base[ax] - ev[ax] for ax in calib},
                "dlat":   base["p50"] - ev["p50"],
                "dmem":   base["mem"] - ev["mem"],
            }
    p = {m: 16 for m in modules}
    while True:
        cand = []
        for m in modules:
            if p[m] == 8:
                for b in (4,):
                    cand.append((m, b, table[(m, b)]))
            elif p[m] == 16:
                for b in (8,):
                    cand.append((m, b, table[(m, b)]))
        if not cand:
            break
        # 选「单位延迟节省风险最小」且不破分轴上限的
        cand.sort(key=lambda x: risk_per_ms(x[2]))
        moved = False
        for m, b, ev in cand:
            if ev["dlat"] <= 0:
                continue
            if any(ev["dscore"][ax] > axis_eps for ax in calib):
                continue                            # 该轴风险超限，跳过
            p[m] = b
            moved = True
            break
        if not moved:
            break
    return p
```

### 4.3 任务条件 foveation + 缓存（UIP-18 + UIP-19）

```python
def foveated_encode(frames, lang, ee_uv, cache, enc):
    zs = []
    for cam, img in frames.items():
        roi = roi_from(lang, ee_uv[cam], img.shape)      # 目标物体 + 夹爪
        fg, bg = crop(img, roi), complement(img, roi)
        event = frame_diff(bg, cache.prev_bg[cam]) > DELTA
        if event or cache.miss(cam):
            b = "fp8" if cam.startswith("wrist") else "int8"
            z_bg = enc(bg, res=img.shape[0] // 4, precision=b)
            cache.put(cam, z_bg)
            cache.prev_bg[cam] = bg
        else:
            z_bg = cache.get(cam)
        z_fg = enc(fg, res=HIGH, precision="fp8" if cam.startswith("wrist") else "int8")
        zs.append(fuse(z_bg, z_fg, event))                # event 同时上报给验证器
    return zs
```

### 4.4 量化-闭环协同（UIP-20）

```python
class QCLPolicy:
    """A4 约束下的保守实现：k 在握手时固定；量化收益用于投机预计算。"""
    def __init__(self, policy, k_declared, verifier, precompute=True):
        self.policy, self.k = policy, k_declared
        self.verifier, self.precompute = verifier, precompute

    def reset(self):
        self.policy.reset(); self.cache = {}; self.pending = None

    def get_action(self, obs):
        # 若上一块执行期间已按「预测观测」预生成下一块，先做一致性校验
        if self.pending is not None and self.pending.matches(obs):
            return self.pending.actions
        if self.precompute:
            self.pending = self.policy.speculate_next(obs)
        return self.policy.get_action(obs)[: self.k]   # 严格按声明块长
```

> 若确认评测允许返回 **≤ 声明块长** 的块（A4 不成立），则把 `self.k` 换成阶段自适应值：接触密集步 k=2–3，远距离搬运 k=6–8；否则一律固定 k，量化收益只用于投机与并发。

## 5. 实验设计 E201–E209

| 实验 | 对照 | 处理 | 主要指标 | 目标（预设，非结果） |
|---|---|---|---|---|
| E201 | FP16 全模型 | 全模型朴素 INT8 | 成功率/步骤分/延迟/显存 | 证明「一刀切」有风险，作为反例 |
| E202 | 朴素 INT8 | **UIP-16 ASQ**（动作头 FP16） | 分轴 Δscore、动作抖动 J | 干净轴 Δ≤2 分；接触步抖动不升 |
| E203 | 干净校准集 | **UIP-17 GAC** 五轴校准 | 各轴量化 gap | 最差轴 gap 相对 E201 降 ≥50% |
| E204 | 全图统一分辨率 | **UIP-18 TCFQ** | token 数/延迟/步骤分 | token −50%，步骤分不降 |
| E205 | 全部视角同精度 | **UIP-19 VPG** | 显存/腕部接触步成功率 | 显存 −30%，腕部步骤分不降 |
| E206 | PTQ | QAT + 动作/时序一致性蒸馏 | 分轴 Δscore、抖动 | 最差轴 gap 再降，抖动下降 |
| E207 | 固定 k + 无预计算 | **UIP-20 QCL**（投机） | p50/p95 延迟、重做率 | p95 −30%，重做率不升 |
| E208 | 单端口 | 多端口共享量化骨干 | 吞吐、p95、端口公平性 | 吞吐 +50%，p95 不超阈值 |
| E209 | 各模块单独 | 联合消融（16+18+19+20） | 综合榜单代理 | 验证交互增益/冲突 |

**必须报告的诊断量**：

- 分轴量化 gap：$R_{\text{axis}}$ 的均值与最大值（不要只报平均）。
- 延迟分布：p50、p95、每端口隔离后的方差。
- 动作稳定性：抖动 $J$、重复动作率、重做率 $\rho_{\text{redo}}$。
- 缓存事件质量：$e_t$ 的召回率/误报率（相对真机干扰标注或 DRF 仿真标注）。

## 7. 合规与红线

- **单模型**：量化是同一模型的不同数值表示，不应算多模型；但**外部 ROI 检测器、外部 VLM 验证器**有合规风险，优先用主骨干交叉注意力与几何规则。
- **动作头不量化**：H_act 与最后融合层保 FP16；这是硬约束，不是调参项。
- **接口形状**：返回块长/dtype/shape 严格按 README；量化不改变接口契约。
- **缓存隔离**：多端口并发时，每端口的视觉缓存、KV、历史必须隔离；共享缓存会串味并伤可信度。
- **未取到的手册**：评测轮次/时限/控制频率、`action_chunk_size` 是否必须精确、`metadata` 可变范围，仍待飞书手册公开后核实（A4 的成立与否直接决定 UIP-20 的形态）。

## 9. 本轮最大风险 & 押注

**一句话**：如果只盯「干净验证集上的平均精度」，量化会把误差悄悄搬到未见物体/背景这两条真正计分的泛化轴上——模型在本地看起来无损，提交后却在该轴崩掉。

**→ 本轮最值得押注**：**UIP-16 ASQ（动作头 FP16 的非对称量化）× UIP-17 GAC（五轴校准）× UIP-18 TCFQ（foveation + 缓存失效即撤回候选）** 这一组合。它同时满足三个条件：① 完全落在选手的离线算力与 API 权限内；② 直接服务于 v2 旗舰「更频繁重观测」的延迟预算；③ 把「视觉编码器看哪里」与「人为撤回检测」用同一个变化信号耦合起来，形成别人不容易同时复制的系统级优势。
