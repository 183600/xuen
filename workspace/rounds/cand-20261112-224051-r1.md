# 新灵感循环 · 第 1 轮（总第 3 轮迭代，v3）——「低延迟推理」×「协同控制」

> 承接第 2 轮 v2（UIP-01′~15）。本轮**不换题**，而是给 v2 补两条物理腿：① **低延迟推理**把"算力节省"变成"控制带宽"；② **协同控制**把"人为干扰"从噪声升级为**有相位、有预算的共处智能体**。两词合流得到本轮旗舰 **UIP-19 · CIR（承诺—打断竞赛）**：与规则里白纸黑字的"反向撤回"抢时间，把已完成进度**尽快变成不可逆**；而能否抢赢，取决于推理延迟预算（UIP-16/17）与对手相位预测（UIP-18）。

---

## 0. 先给直觉，再给定义

**低延迟推理的直觉**：评测端是「看一帧 → 你回一整块动作 → 它闭眼执行完 → 再看一眼」。你的"眼睛"被 `动作块执行时间 + 推理时间` 共同蒙住。推理慢，就被迫闭眼更久；闭眼越久，人为干扰在你睁眼之前把进度撤得越干净。所以**低延迟不是省电，而是买反应频率**——省下的每一毫秒都能兑换成"更早看见撤回、更早重做"。

**协同控制的直觉**：那个"合上后再打开、拉上后再拉开"的人，不是环境噪声，而是**与你共享工作空间的第二个控制器**：他有感知延迟、有动作预算、有触发相位（多数在你"刚完成"的瞬间出手）。赛制是单机器人，因此"协同"落到三层：
1. **人-机共处/对抗**：把他建模为对手，抢在他出手前锁死进度，或预判后让路；
2. **臂-腰(pivot)-手内部协同**：固定底座下这三者是冗余协同链，可扩可达域、吸收接触反力；
3. **多端口服务协同**：N 个端口共享一张卡，是"共享资源 + 各自低延迟"的协同调度。

**两者合流的洞见**：存在一场竞赛——你的 `完成→不可逆` 时间 `T_c`，对上他的 `看见→撤回` 时间 `T_h`。规则已证他专挑"可逆的完成态"下手（叠好翻开、拉上拉开、合上打开）。**治本不是更快地重做，而是让 `T_c < T_h`，使"重做"根本不发生**：低延迟推理缩短 `T_c`，相位建模预测 `T_h`，不可逆微技能直接抹掉他的收益。

## 1. 严谨定义（本轮核心形式化）

### 1.1 延迟分解与反应滞后
- 单次调用延迟：`L_call = L_obs(JPEG编解码+网络) + L_pre + L_infer + L_post`。
- 有效反应滞后（物理事件→首个纠偏动作，最坏情形事件落在块首）：
  `ρ = T_a·dt + L_call + L_verify`。
- 开环块等价于时长 `T_a·dt` 的**零阶保持器（ZOH）**；对时间常数 `τ` 的一阶对象，单块内"盲执行"的鲁棒性约按 `e^{−T_a·dt/τ}` 衰减，扰动抑制带宽 `ω_b ≈ 1/ρ`。
- **延迟可行性条件**：`ρ < T_h / κ`（`κ≈3` 经验裕度，源自采样需快于对象特征时间数倍）。由此给出**块长预算**：
  `T_a·dt < T_h/κ − L_call − L_verify`。
- **延迟—带宽转换（LITB）**：推理把 `L_call` 降低 `ΔL`，等价于"保持 `ρ` 不变时把 `T_a` 提高 `ΔL/dt`（换吞吐）"或"保持 `T_a` 时提高重观测频率"。本轮**优先把 `ΔL` 兑换成验证频率**，因为撤回检测的边际收益高于吞吐。

### 1.2 进度可逆度与不可逆算子
对状态 `s` 定义**可逆度** `r(s) ∈ [0,1]`：`r=1` 表示"对手一步即可完全撤销"，`r=0` 表示"撤销成本超过其动作预算"。
**不可逆算子** `I = {seat(压合), latch(扣合), close(合盖), insert-fully(插到底), place-inside(放入容器), possess(持续持有)}`；执行 `I` 使 `r→0`。
对无法真正不可逆的任务（如叠毛巾/叠碗/整理），用**占有（gripper 不松）**或**守卫位姿**抬高对手的撤销代价，即把 `r` 从 1 压到中等。

### 1.3 对手作为相位共智能体
对手策略 `π_h(a | s, φ)`，相位 `φ ∈ {approach, intervene, retreat}`；由相机观测量（手/物运动）估计 `φ̂` 与剩余干预时间 `τ̂_h`。
策略动作空间扩为 `{advance, commit, yield, preempt}`：
- `advance`：正常推进；
- `commit`：完成同时锁死（不可逆）；
- `yield`：让路并预置到"即便被撤也最省重做"的位置；
- `preempt`：在对手必经处先占位/挡住。

### 1.4 承诺—打断竞赛（CIR）
第 `i` 步分值 `score_i`，完成时刻 `t_i`，承诺耗时 `T_c,i`；对手撤回时间 `T_h,i ~ F_h`（由 `φ̂` 估计）。该步保存概率 `p_i = P(T_c,i < T_h,i)`。
**期望步骤分**：`E = Σ_i score_i · p_i`。
**调度含义**：延迟预算和不可逆动作应优先投到"**高分值 × 高干预概率**"的步（v2 §2 已证末步分值恒 ≥ 前序）。这与 v2 的 UIP-01′/09′ **互补而非重复**：01′/09′ 负责"被撤回了要能重做"（兜底），CIR 负责"让它不被撤回"（治本）。

## 2. 瓶颈假设（本轮更新）

- **H5（最高杠杆）**：真瓶颈不是平均延迟而是**延迟方差**（评测可信度明确看逐步延迟波动）；方差大 ⇒ `ρ` 不可预测 ⇒ CIR 的 `T_c` 无法保证。
- **H6**：人为干扰有**相位结构**（集中在"完成瞬间"），可用轻量估计器预测；预测提前量 > 0 时，commit 可先行一步。
- **H7**：低延迟的代价是模型容量/蒸馏损失，可能牺牲未见物品泛化（v2 的 `unseen_object` 轴）——存在"**延迟—泛化前沿**"。
- **H8**：固定底座下 pivot 与手臂是冗余协同链；纳入协同控制可扩可达域/吸收接触反力。但 pivot 是否在接口动作内需核实（v2 记为可用，仍标"待真机确认"）。

## 3. 候选合并 → v3 清单

新增 6 个：**UIP-16 LITB**（延迟→带宽转换）、**UIP-17 SSAD**（自投机动作解码）、**UIP-18 PACE**（相位感知共智能体）、**UIP-19 CIR**（承诺—打断竞赛，旗舰）、**UIP-20 WBCC**（全身协同控制）、**UIP-21 FMS**（多端口公平调度）。

详见产物区。v2 的 UIP-11 GSO / UIP-12 DRF 仍是本轮的**离线测量与造数据底座**，不重复展开。

## 4. 本轮最大风险（一句话）

若把"延迟预算"押在**相位预测**上，而真机人工干扰的时机/速度分布与仿真不符，那么过早 commit 会锁死错误状态、过晚 commit 等于没锁；CIR 的收益会被"预测误差 × 不可逆动作"放大成更大的步骤分损失。

## 1. 旗舰深潜：UIP-19 · CIR（Commitment–Interruption Race）

**目标函数**：`max_π E[Σ_i score_i · P(T_c,i < T_h,i)]`。这不是"任务成功率最大化"，而是"**期望步骤分最大化**"——与榜单第二口径直接对齐。

**三条腿**：
1. **缩短 T_c**：`T_c,i ≈ (块剩余时间) + L_call + L_verify + Δ_act(commit)`。用 UIP-16 压块间剩余、UIP-17 压 `L_call`、把 completion 与 commit **融合成一段连续动作**（`completion-commit fusion`，避免"完成后等下一次调用再锁"这段致命空窗）。
2. **估计 T_h**：UIP-18 从手/物运动估计 `φ̂`、`τ̂_h`；把 `F_h` 当作时变分布，`τ̂_h < 窗口` 即触发抢占。
3. **抹掉收益 / 抬高代价**：UIP-19 的不可逆算子 `I`；不可逆时用占有/守卫位姿把 `r` 压低。

**与 v2 的差异**：v2 的 01′/09′ 是"事后重做"（reactive redo）；CIR 是"事前不可逆"（proactive commit）。两者组合后系统行为是"**能锁先锁，锁不住才重做**"。

**风险**：`r` 与 `φ` 的误判会被不可逆动作放大。护栏：只在 `conf>c_thr` 且 `r>r_thr` 且 `τ̂_h` 落在窗口内才 commit；对不可逆动作设"最大误锁次数"，并用 UIP-11 离线回放估计误锁代价。

## 2. 低延迟推理：UIP-16 LITB / UIP-17 SSAD

### UIP-16 · LITB（Latency→Bandwidth Transducer）
- **机制**：在线估计 `L_call`（EMA）与 `L_verify`，由可行条件反解块长：
  `k* = clip( (T_h/κ − L_call − L_verify) / dt , 1, K_MAX )`。
  并把 `ΔL = L_baseline − L_now` 的**用途做显式记账**：默认兑换为"更高验证频率"，仅在远离接触步时兑换为"更大块长/吞吐"。
- **与 v2 ACS 差异**：ACS 是"按阶段拍脑袋选 k"；LITB 给出**可证伪的预算不等式**，并把延迟当作可分配资源。
- **可行性**：高（纯策略侧调度；`metadata` 的 `action_chunk_size` 握手中定全局 `K_MAX`，每次可返回 `≤K_MAX` 的块）。
- **风险**：`T_h`/`κ` 标定误差会系统性选错 k ⇒ 用真机撤回视频估 `F_h`，并留安全裕度。

### UIP-17 · SSAD（Self-Speculative Action Decoder）
- **机制**：同一骨干上挂一个**极小草稿头** `g`：先出整块草稿 `Â`；全模型 `f` 只对"草稿置信度低/接触密集"的时步精修；若 `‖f−g‖<ε`（逐元素或任务空间误差）则接受草稿。再加**层间早退**：动作头熵低于阈值且所有时步可靠时提前出层。
- **合规**：草稿头是主骨干的子网/蒸馏头，**不引入外部大模型**，仍属"单模型多任务"。
- **与 v2 差异**：v2 的实时性只做"工程隔离/削载荷"；SSAD 直接压 `L_infer` 与**延迟方差**（H5）。
- **风险**：草稿在接触突变处失准 ⇒ 只允许在低风险时步接受草稿，接触步强制精修。

## 3. 协同控制（一）：UIP-18 · PACE（Phase-Aware Co-agent Estimator）

- **机制**：轻量时序头（复用主骨干特征，零外部模型）输出 `φ̂`、`τ̂_h`、`conf`。训练标签可用 UIP-12 DRF 生成的"干扰发生时刻"自动弱标注（无需人工标注）。
- **决策接口**：把 `φ̂, τ̂_h` 交给 CIR 的 `{advance, commit, yield, preempt}` 选择器。
- **与 v2 差异**：v2 的 09′ 只做"检测到撤回→重做"；PACE 做"**预测将撤回→提前应对**"，把反应式变预测式。
- **可行性**：中高（相位是粗粒度三分类 + 一个时间回归，数据可由仿真造）。
- **风险**：真机人手多样性远超仿真 ⇒ 训练时对"手出现轨迹/速度/时机"做域随机化，并允许 `conf` 低时退回纯 09′。

## 4. 协同控制（二）：UIP-20 · WBCC（Whole-Body Cooperative Control）

- **机制**：`q=[q_arm, q_pivot, q_hand]`，任务 `x=hand pose + finger closure`。用**加权伪逆**在冗余链上分配：
  `q̇ = W⁻¹Jᵀ(JW⁻¹Jᵀ)⁻¹(ẋ_d − J̇q̇) + (I − W⁻¹Jᵀ(JW⁻¹Jᵀ)⁻¹J)·null`。
  权重 `W` 按阶段切换：**插入/合盖**时降低 pivot 刚度让腰吸收反力、抬高手部轴向刚度；**大范围搬运**时转 pivot 让手臂远离关节限位、扩大可达域。
- **与 v2 差异**：v2 完全没碰低层协同（只谈块长/验证）。这是"固定底座桌面任务"里被忽视的自由度。
- **可行性**：中（需 `pivot` 在接口动作内 **[待核实]**；若不可用，退化为纯臂内冗余分配）。G1 在 Gazebo 支持低层位置/力矩控制，可先在 UIP-11 验证。
- **风险**：pivot 与手臂的协同若时标不匹配会引入额外超调 ⇒ 用阻抗分配而非位置硬切，并在仿真里扫 `W`。

## 5. 协同控制（三）：UIP-21 · FMS（Fair Multi-tenant Serving）

- **机制**：N 端口共享一次前向（提高吞吐、摊薄 `L_infer`），但**每个端口独立 KV/历史/缓冲区**，绝不共享可变状态；调度用**带截止期的加权公平队列**，目标 `min max_i p99(L_i)` 且约束 `isolation_violations = 0`。
- **与 v2 差异**：v2 的 08′ 只讲"隔离"，未把"公平 + 截止期 + 方差"形式化；FMS 把多端口当**协同资源分配**问题。
- **风险**：有状态策略的连续批处理易串味 ⇒ 只做"块级批处理 + 每端口独立 KV"，并加隔离断言测试。

## 6. 关键算法（伪代码）

```python
class CIR_Policy:                       # UIP-19 = 16 + 17 + 18 + 01'/09'
    def __init__(self, policy, ssad, pace, verifier, dt, tau_h,
                 kappa=3.0, k_max=8, c_thr=0.7, r_thr=0.6):
        self.policy, self.ssad, self.pace = policy, ssad, pace
        self.verifier = verifier
        self.dt, self.tau_h, self.kappa = dt, tau_h, kappa
        self.k_max, self.c_thr, self.r_thr = k_max, c_thr, r_thr
        self.L_ema, self.verify_ms, self.g = 0.0, 0.0, 0

    def reset(self):
        self.policy.reset(); self.ssad.reset(); self.g = 0; self.L_ema = 0.0

    def _k(self):                        # UIP-16 LITB：延迟可行性条件反解块长
        return int(max(1, min(self.k_max,
            (self.tau_h / self.kappa - self.L_ema - self.verify_ms) / self.dt)))

    def get_action(self, obs):
        t0 = now()
        k = self._k()
        phi, tau_hat, conf = self.pace(obs)          # UIP-18
        r = self.reversibility(obs, self.g)          # 1=极可逆, 0=已锁死
        if conf > self.c_thr and r > self.r_thr and tau_hat < self.dt * k * 1.5:
            out = self.commit_fused_chunk(obs, k)     # 完成+锁死一体，抢 T_c<T_h
        else:
            out = self.ssad.get_action(obs, k)        # UIP-17：草稿+精修+早退
        self.L_ema = 0.9 * self.L_ema + 0.1 * (now() - t0)
        if self.verifier.done(obs, self.g):            # 兜底：UIP-01'/09'
            self.g += 1
        return out
```

```python
# UIP-20 WBCC：冗余链加权伪逆（含 arm+pivot）
def wbcc(q, qd, x_des, W):               # W = diag(hand, pivot, ...) 按阶段设
    J = jacobian(q)                      # d x n
    A = J @ np.linalg.inv(W) @ J.T
    Jinv = np.linalg.inv(W) @ J.T @ np.linalg.inv(A)
    null = (np.eye(len(q)) - Jinv @ J) @ qd
    return Jinv @ (x_des - fk(q)) + null

# UIP-21 FMS：共享前向、严格隔离、截止期公平
def serve(ports):
    reqs = [p.pending() for p in ports]
    batch = pack_ragged(reqs)            # per-port KV/历史各自独立
    out = model.forward(batch)           # 单次前向摊薄 L_infer
    for p, o in zip(ports, scatter(out, ports)):
        assert p.state_unchanged_except_own(o)   # 隔离断言
        p.deadline_aware_advance()
```

## 8. 合规与风险

- **单模型合规**：SSAD 草稿头、PACE 相位头、WBCC 均是主骨干的子网/控制律，**不引入外部大模型**；所有头共享一条骨干。
- **延迟—泛化权衡（H7）**：为压 `L_infer` 的蒸馏会伤 `unseen_object`；用 E116 画前沿，禁止"用泛化换延迟"越界。
- **接口红线**：块长/形状/dtype/token 严格按 README；返回块长与声明不一致、动作统计异常会伤可信度（UIP-15 护栏）。
- **事实边界**：`pivot` 可发、干扰是否计入正式计分、`T_h` 真机分布，均 **[待核实]**；不得把推导写成已证事实。

## 9. 资源与时间线（粗排）

- 第 1–2 周：在 v2 的 GSO 骨架里加 WBCC 的 `pivot` 通道与几何判分；标定 `dt/T_h/κ`。
- 第 3–4 周：LITB + SSAD 上线，测延迟分解与方差（E109/E110）。
- 第 5–6 周：PACE 相位头用 DRF 弱标注训练；接 CIR 决策（E111/E112）。

- 第 9 周起：预约真机校准 `r/F_h` 与 GSO 代理相关性（E117）。

## 10. 本轮最大风险 & 押注

**一句话**：CIR 把收益押在"相位预测 × 不可逆动作"上，预测一错，不可逆动作反而把错误锁死，步骤分损失被放大。

**→ 押注：UIP-19 CIR（由 UIP-16 LITB 控时、UIP-17 SSAD 压延迟、UIP-18 PACE 预测、UIP-20 提供不可逆执行），以 v2 的 UIP-11 GSO + UIP-12 DRF 做离线校准与造数据**——它把"人为撤回"从"事后重做的成本问题"改写为"事前抢时间的竞赛问题"，正好用满本轮两个灵感词，且全部落在选手 API 与离线算力之内。
