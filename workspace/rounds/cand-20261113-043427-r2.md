# 第 3 轮迭代（灵感循环 v3：「Isaac Sim」×「状态隔离」）—— 从「仿真裁判」到「三域隔离的对账系统」

> 承接 v2（UIP-01′~15）。v2 的旗舰是「扰动撤回检测-重做」，由 Gazebo 判分（UIP-11）与扰动-恢复数据工厂（UIP-12）支撑；v2 最大的未解问题是：**裁判本身是否可信？** 本轮两个灵感词看似是“换更高级的仿真器 + 修多端口 bug”，但核对 Unitree 的 Isaac Lab 仓库与提交 README 后，得到两个反直觉结论：
>
> 1. **Isaac Sim 的真正杠杆不是“更高保真的渲染”，而是“接口同构 + 可回放 + 内置步骤奖励”。** `unitree_sim_isaaclab` 与真机共用 DDS 话题和 teleimager 相机服务，支持回放数据、在回放时改光照/相机重渲染，并用 `get_step_reward_value` 直接读离散步骤奖励。这些能力让它可以测试**整个提交服务器**，而不只是模型。
> 2. **状态隔离不是工程卫生，而是验证的认识论前提。** 如果验证器的“进度状态”与策略的“潜状态”是同一个可变对象，验证器就会把策略的偏差合理化；如果仿真影子由策略动作驱动、又与真实观测共享同一状态，它就会继承策略的误差。**没有隔离，`regressed` 只是一个自证预言。**
>
> 因此本轮不是“把 Gazebo 换成 Isaac”，而是把 Isaac 降级为**受隔离约束的回放/反事实实验室**，把状态隔离升级为**一等研究原则**。

## 1. 上轮清单诊断（升级 / 修剪 / 封存）

## 2. 直觉解释

### 2.1 Isaac Sim：不是“更漂亮的 Gazebo”，而是“同构的回放实验室”

最直觉的用法是“Isaac 更真，所以在 Isaac 里训练/评测更好”。这恰好是最危险的用法：**渲染更真 ≠ 动力学更真 ≠ 接触更真**。G1 桌面任务的成败大量取决于接触（插入、拧动、折叠、拉链），而接触正是 sim-to-real gap 最大的地方。把 Isaac 当“更高保真的成败裁判”，只会把 v2 的“仿真自欺”风险放大。

更合适的直觉是：Isaac 的稀缺价值在于**接口同构**。它和真机说同一种 DDS、用同一个 teleimager 相机服务、支持把 policy 当动作源；它还能**回放真实轨迹**并在回放时改光照/相机。于是它最适合做三件“真机很贵、纯数据又做不到”的事：

1. **测整个服务器**：N 端口、token、动作形状、图像键、延迟——这些是比赛真正会 reject/扣可信度的地方；
2. **读步骤奖励**：`get_step_reward_value` 给出离散任务奖励，直接对齐步骤分；
3. **做受控反事实**：同一条真实轨迹，改光照/相机/背景重渲染；或在某个时刻注入 `human_*` 撤回，看恢复策略是否真的把进度救回来。

一句话：**Isaac 不是“更好的裁判”，而是“可隔离、可回放、可反事实的实验台”。**

### 2.2 状态隔离：三本账，只许对账，不许互改

最直觉的理解是“每个端口 `reset()` 一下、加把锁”。这只覆盖了**并发**，没有覆盖**认识论**。真正的隔离要回答：

- **真实进度**（世界到底完成了什么）由谁记录？
- **策略自述进度**（模型以为完成了什么）存在哪里？
- **仿真影子进度**（数字孪生认为完成了什么）又存在哪里？

如果这三者共用一块可变状态，就会出现三种自欺：

1. **验证器合理化**：策略把“没插进去”编码成“插进去了”，验证器读同一个潜变量，于是也认为完成了；
2. **影子继承误差**：仿真影子用策略的动作推进，又把真实观测写回同一状态，误差互相污染；
3. **端口串味**：共享模型的 KV/历史/`reset` 没隔离，A 端口的 episode 影响 B 端口的动作，延迟和动作统计出现无法解释的抖动。

正确的直觉是：**三本独立的账本，只允许“签名事实”跨账本流转，永远不允许原始潜状态互相写入。** 真实账本只能由可观测谓词/带时间戳的见证追加；仿真账本只读，且只作为“咨询意见”；策略账本可以错，但它的错误不能污染另外两本。**隔离不是为了跑得快，而是为了让“撤回”可被证明。**

## 3. 严谨定义

### 3.1 状态胶囊与隔离契约

**定义 1（状态胶囊）**：一个状态胶囊 `C = (S, owner, lifetime, reset, fp)`，其中 `S` 是可变态集合，`owner ∈ {port, episode, oracle, shared-immutable}`，`lifetime ∈ {process, episode, step}`，`reset: S → S_0` 是复位映射，`fp: S → {0,1}^k` 是指纹函数。

**定义 2（隔离契约）**：隔离契约是一个四元组 `K = (C, E, R, F)`：

- `C = {C_1..C_m}` 是胶囊集合；
- `E ⊆ C_i × C_j × Payload` 是允许的跨胶囊通道，`Payload` 只能是**签名事实** `w = (predicate, t, conf, source)`（不可变、带时间戳、带来源）；
- `R` 是每端口的复位协议；
- `F` 是每端口的确定性种子派生 `seed_p = PRF(master_seed, p)`。

**隔离成立**当且仅当对任意端口 `p ≠ q`、任意时刻 `t`：

```text
s_{t+1}^p = f_p(s_t^p, o_t^p, a_{t-1}^p)          # 不依赖 s^q
reset_p(s) = s_0,  ∀s                            # 复位是常值映射
a_t^p ⟂ s_t^q | (o_{0:t}^p, s_{t-1}^p)           # 输出条件独立
fp(s_t^p) 可由 seed_p 复现                         # 可复现
```

且跨胶囊写入只允许 `E` 中的签名事实，`oracle` 胶囊对 `port/episode` 胶囊**只读**。

**定义 3（泄漏与复位污染）**：设同一组输入在“单端口串行”与“N 端口并发”下的每端口输出分布分别为 `P_p(a)` 与 `P_p^N(a)`，定义

```text
L_out   = max_p TV(P_p(a), P_p^N(a))
L_state = max_{p≠q} I(fp(s^p); fp(s^q))
R_reset = max_p KL(P(a | s_0) ‖ P(a | s_reset_after_episode))
```

理想隔离要求 `L_out = L_state = R_reset = 0`。工程上可用 canary、置换、kill、reset-fuzz 做**可证伪的近似**（见 UIP-18 SILK）。

### 3.2 三域进度账本

**定义 4（三域状态）**：对子目标 `g`，维护三个**物理隔离**的状态：

- `ℓ_t`：**真实账本**，只追加签名事实，单调除非出现 `undone(g)` 见证；
- `b_t`：**策略信念**，模型内部潜状态/预测头，允许错；
- `σ_t`：**仿真影子**，Isaac 回放/反事实得到的状态，物理更真但受 sim gap 影响。

只有 `ℓ_t` 能决定“是否已完成”；`b_t` 只能提示“可能完成/可能撤回”；`σ_t` 只能提示“物理上是否可逆/是否被遮挡”。

**定义 5（三角校验）**：在检查点 `t`，令 `r = status(ℓ_t,g) ∈ {done, undone, unknown}`，`b = status(b_t,g)`，`s = status(σ_t,g)`。决策表：

| 观测组合 | 判定 | 动作 |
|---|---|---|
| `r=undone` 且 `ℓ` 曾有 `done(g)` | **regressed** | 重做 `g`（受 CSG 预算约束） |
| `r=done` 且 `b≠done` | **belief_lag** | 前进，并修正 `b`（信任真实） |
| `r=undone` 且 `b=done` | **hallucinated_done** | 重新核验；必要时重做 |
| `r` 与 `s` 连续 `m` 次不一致 | **sim_drift** | 降低 `σ` 权重；不写 `ℓ` |
| 仅 `s=done`、`r=unknown` | **advisory_only** | 不前进；加大核验频率 |
| `r=done` 且 `b=done` | **advance** | `g ← g+1`，清空重做计数 |

**关键不变量**：`σ` 和 `b` **永远不能写 `ℓ`**；`ℓ` 的每次写入必须携带一个来自真实观测或人工标注的见证。这条不变量使 `regressed` 可审计、可回放、可证伪。

### 3.3 保真阶梯与信任权重

**定义 6（保真阶梯）**：用 `L0..L3` 表示四层代理：

- `L0` 几何/规则谓词（最便宜、最结构）；
- `L1` Gazebo 物理（低成本、可并行、接触一般）；
- `L2` Isaac Lab（高保真视觉/接触、接口同构、内置步骤奖励）；
- `L3` 真机锚点（最贵、最可信、样本最少）。

对每层 `L`，在真机锚点集上估计步骤分相关性 `ρ_L = corr(score_L, score_real)`，定义信任权重

```text
w_L = max(0, (ρ_L − ρ_0) / (1 − ρ_0))
```

只有 `w_L > τ` 的层才允许作为“相对排序”信号；任何层都不得单独作为“绝对成败”结论。

### 3.4 隔离感知的真实→仿真视觉回放

**定义 7（R2S-VX 回放）**：给定真实轨迹 `τ = {(o_t^{1:4}, q_t, a_t)}_{t=1}^T`、场景 `S`、渲染器 `R`、视觉扰动 `δ`（光照/相机/背景），定义重渲染观测

```text
õ_t = R(S, q_t, δ)
```

其中 `q_t` 使用**真实机器人状态**做运动学回放，**不使用仿真动力学**。于是：

- 动作/接触语义来自真实数据（无动力学 sim-to-real gap）；
- 只有视觉状态被合成；
- `δ` 只存在于仿真平面，不写回真实/策略平面；
- 每个新视角 `δ` 都是同一标签的“新视图”，用于训练视觉编码器，而不是新任务。

这是 **“真实动力学 + 仿真视觉”**，与“仿真动力学 + 仿真视觉”的常规 DR 有本质区别。其代价是需要物体位姿：优先用 6D 位姿跟踪/场景重建；若拿不到，则退化为“静态物体 + 机器人运动”的相机/光照扩增，或只对几何已知的原型任务使用。

## 4. 证据驱动的假设

- **H1（隔离是承重墙）**：在 N 端口并发下，共享状态实现会出现可测的 `L_out/L_state/R_reset > 0`，并伴随 `regressed` 误报率上升；PSI 能把三者压到接近 0。**这是本轮最可证伪、也最容易被对手忽略的点。**
- **H2（三角 > 单验证器）**：在脚本化 `human_*` 撤回下，TSI-V 的步骤分与误重做率优于单一视觉验证器；增益主要来自“真实账本 + 撤回见证”，仿真影子只在接触歧义时提供边际增益（对应 `w_L` 较低）。
- **H3（Isaac 的杠杆是接口与回放，不是分辨率）**：ILO 的价值主要来自“测整个服务器 + 内置步骤奖励 + 回放重渲染”，把渲染从 photoreal 降到简单材质，性能不应显著下降；若显著下降，说明我们在用视觉保真度掩盖动力学问题。
- **H4（真实动力学 + 仿真视觉 > 全仿真）**：在背景/光照/相机位移轴上，R2S-VX 的迁移优于纯仿真 DR，因为它避免了动力学错配；但在大幅度物体位姿变化上，若位姿跟踪失败，优势会消失。
- **H5（隔离是可信度资产）**：进程/命名空间隔离 + 每端口投机缓存失效，会降低 P95 延迟抖动与动作异常率；共享状态即使不影响成功率，也会伤可信度。

## 5. 候选草案与合并

围绕两个词发散 9 个草案：

| 草案 | 来源词 | 判断 | 去向 |
|---|---|---|---|
| 在 Isaac 里训一个更强策略 | Isaac | ❌ 成本高、sim-to-real 风险最大 | 删除 |
| Isaac 当作步骤分神谕 | Isaac | ✅ 内置奖励 + 回放 | UIP-11′ ILO |
| 回放真实数据 + 改光照/相机重渲染 | Isaac | ✅ 最高性价比、避开动力学 gap | UIP-16 R2S-VX |
| Isaac 注入 `human_*` 撤回 | Isaac | ✅ 补最大数据空白 | UIP-17 ICDR |
| 每端口独立进程 | 隔离 | ✅ 最稳但显存贵 | UIP-08″ PSI（方案 A） |
| 共享模型 + 全局 `reset` | 隔离 | ❌ 明文红线 | 删除 |
| 共享模型 + 每端口胶囊 + 请求标签 | 隔离 | ✅ 省显存，但要 SILK 证明 | UIP-08″ PSI（方案 B） |
| 三域账本 + 三角校验 | 隔离 | ✅ 核心 | UIP-01″ TSI-V |
| Canary/置换/kill/reset-fuzz 测试 | 隔离 | ✅ 把隔离变成可证伪 | UIP-18 SILK |

**修剪原则**：任何“运行时依赖仿真/外部大模型”的方案不进提交；任何“共享可变态但只靠 `reset()` 兜底”的方案一律视为未隔离；任何“为了仿真而仿真”的大场景建设，先问它是否改变**步骤分排序**。

## 6. 本轮最大风险

**一句话**：把 Isaac 当成“更高保真的裁判”、把状态隔离当成“加锁 + `reset()`”，会同时招致 sim-to-real 自欺与多端口泄漏；真正的护城河是“三账本对账 + 隔离契约 + 真机锚点”，而不是仿真分辨率。

## 0. 先修正 v2 的三处硬伤（本轮必须承认）

在把新想法接上去之前，先承认 v2 里三个与 README 契约不一致的地方。它们不改变 v2 的方向，但会改变实现：

1. **`action_chunk_size` 是握手时固定的全局常量，不能按阶段自适应。** v2 的 UIP-13 说“按阶段动态选 `k`、全局最大 `k`、每次返回 ≤k 步”。但 README §3 要求每次返回的数组形状为 `(T_a, …)`，`T_a` 在 `metadata` 里只读一次。**运行期不能改 `T_a`，也不应返回短块。** 因此验证的时间分辨率被量化成 `T_a`：策略只能在每个块边界看到新观测。UIP-13 必须重新定义为“**计算调度 + 块内安全设计**”，而不是“变长块”。
2. **v2 旗舰伪代码 `return self.buf.pop(0)` 返回的是单步动作，不是块。** 实际接口要求返回 `(T_a, …)` 的完整块。正确的做法是：内部维护 `T_a` 长度的计划，`get_action` 一次返回整块；块尾动作必须是“安全保持/回撤”形态，以便下一个块边界发现 `regressed` 时机器人仍处于可恢复姿态。
3. **`control_space` 与 `obs_delta_indices` 也在握手时固定。** 这验证了 v2 封存 UIP-10 的判断；同时意味着“按任务切换 obs 键/控制空间”不可行。**单模型、单接口、单块长**是硬约束，所有“多模型/多接口”的设想必须收敛到共享骨干 + 条件化。

> 这三条修正把本轮从“继续堆模块”拉回到可执行：**验证发生在块边界，隔离必须跨块、跨端口、跨仿真/真实平面。**

## 1. 旗舰深潜：UIP-01″ · TSI-V（Triangulated State-Isolated Verification）

### 1.1 机制

把“进度”拆成三个**物理隔离**的账本，只在**块边界**对账：

```text
真实平面 (ℓ)：可观测谓词 + 带时间戳的见证  →  唯一有权写“已完成”
策略平面 (b)：模型潜在信念 / 预测头          →  允许错，不能污染 ℓ
仿真平面 (σ)：Isaac 回放/反事实（异步、只读） →  只作咨询，不能写 ℓ
```

- **真实平面**：每个计分步写 2–5 个几何/语义谓词（如“夹爪夹住耳机盒”“碗 2 叠在碗 1 上”“拉链闭合长度 > L”）。谓词输出三类见证：`done(g)`、`undone(g)`、`unknown(g)`，带时间戳、置信度、来源 `source ∈ {real, human_label, sim}`；但只有 `source ∈ {real, human_label}` 能写 `ℓ`。
- **策略平面**：主骨干的进度头/潜状态；只用于“提示”，不用于“宣布完成”。
- **仿真平面**：Isaac 异步回放当前块，输出物理/几何状态，作为“接触歧义时的第三方意见”。它永远不阻塞控制路径，也永远不被当作绝对成败。

### 1.2 三角决策（块边界执行）

| 真实 `r` | 策略 `b` | 仿真 `s` | 判定 | 动作 |
|---|---|---|---|---|
| `undone` 且 `ℓ` 曾有 `done(g)` | 任意 | 任意 | `regressed` | 重做 `g`（CSG 预算内） |
| `done` | `≠done` | 任意 | `belief_lag` | 前进；修正 `b` |
| `undone` | `done` | 任意 | `hallucinated_done` | 重新核验；必要时重做 |
| `unknown` | 任意 | `done` | `advisory_only` | 不前进；缩小 `T_a`（若尚未握手）或提高谓词密度 |
| `r` 与 `s` 连续 `m` 次不一致 | 任意 | 任意 | `sim_drift` | 降低 `w_sim`；不写 `ℓ` |
| `done` | `done` | 任意 | `advance` | `g ← g+1`；清空重做计数 |

**不变量**：

- `ℓ` 只能追加，不能原地改；`undone` 必须以“新见证”形式追加，保留历史，便于审计。
- `b`、`σ` 对 `ℓ` **零写权限**；跨平面只传签名事实。
- 每次 `regressed` 重做必须记录 `(g, t, witness, 触发平面, 重做次数)`，可离线回放。

### 1.3 伪代码（修正为返回完整块）

```python
class TSIVPolicy:
    """UIP-01″ + UIP-13′ + UIP-15；接口要求每次返回完整 (T_a, …) 块。"""
    def __init__(self, policy, real_v, sim_v, recovery, csg, T_a, m=2):
        self.policy, self.real_v, self.sim_v = policy, real_v, sim_v
        self.recovery, self.csg = recovery, csg
        self.T_a, self.m = T_a, m

    def reset(self):
        # 固定顺序复位，且只触碰 port/episode 胶囊
        self.policy.reset(); self.real_v.reset(); self.sim_v.reset()
        self.ledger.reset()
        self.g = 0
        self.sim_disagree = 0
        self.redo = 0

    def get_action(self, obs):
        # 1) 真实平面 -> 签名见证 -> 账本（唯一写者）
        for w in self.real_v.witnesses(obs, self.g):
            self.ledger.append(w)

        # 2) 块边界对账
        verdict = self._reconcile(obs)

        # 3) 生成完整 T_a 块
        if verdict == "regressed" and self.csg.allow("redo", self.g):
            self.redo += 1
            chunk = self.recovery.chunk(obs, self.g, self.T_a)
        elif verdict == "advance":
            self.g += 1; self.redo = 0
            chunk = self.policy.chunk(obs, self.T_a)
        else:
            chunk = self.policy.chunk(obs, self.T_a)

        # 4) 块尾安全化：最后若干步保持/回撤，便于下块边界纠错
        chunk = self.csg.shape(chunk, T_a=self.T_a, tail="hold")

        # 5) 异步仿真影子：不阻塞控制路径，不写账本
        self.sim_v.submit(obs, chunk, self.g)
        return chunk

    def _reconcile(self, obs):
        r = self.real_v.status(obs, self.g)       # done / undone / unknown
        b = self.policy.belief_status(obs, self.g)
        s = self.sim_v.latest_status(self.g)      # 可能为 None（异步/陈旧）

        if r == "undone" and self.ledger.ever_done(self.g):
            return "regressed"
        if r == "done" and b != "done":
            return "advance"                      # belief_lag：信任真实
        if r == "undone" and b == "done":
            return "reverify"                     # hallucinated_done
        if s is not None and s != r:
            self.sim_disagree += 1
            if self.sim_disagree >= self.m:
                self.sim_v.downweight()           # sim_drift：只降权
        return "continue"
```

### 1.4 为什么“隔离”让 `regressed` 可证明

- 若 `r=undone` 且 `ℓ` 曾有 `done(g)`，这是一个**单调性破坏**，必须由一个真实见证解释；策略信念 `b` 无法“撤销”它。
- 若没有隔离，策略可以在同一潜空间里把 `done` 重编码为 `undone`（或反之），账本随信念漂移，`regressed` 就退化为“策略觉得自己退步了”。
- 因此，**`regressed` 的可靠性 = `ℓ` 的写权限隔离 + 见证的来源可审计**，而不是验证器的分类精度。

### 1.5 可行性与风险

- **可行性高**：`reset()`、`get_action()`、块形状都在接口内；真实谓词可用几何/规则，零额外模型；进度头可从主骨干蒸馏。
- **关键约束**：验证只在块边界发生，`T_a` 越大，撤回检测越晚。接触密集任务应选较小的 `T_a`（如 4），搬运/远距离可用较大（如 8–16）；这是**全局一次选择**，需按任务组合折中。
- **风险**：谓词误判 `undone` → 反复重做；用三置信度门限 + 最大重做次数 + 延迟预算（UIP-15）。
- **风险**：仿真影子陈旧 → 用 `m` 次不一致才降权，且永远不写账本。

## 2. 状态隔离工程：UIP-08″ PSI + UIP-18 SILK

### 2.1 两种部署，同一套隔离契约

| 方案 | 拓扑 | 优点 | 代价 | 适用 |
|---|---|---|---|---|
| **A · 进程隔离** | 每端口一个进程，各加载一份模型 | 最强隔离；kill 一个不影响其他；审计简单 | N× 显存/主存；启动慢 | N 小（如 3）、模型轻量 |
| **B · 共享骨干 + 端口胶囊** | 一个后端，N 个轻量端点；每端口独立 KV/历史/缓冲/RNG | 省显存；可批处理 | 必须证明无串味；实现复杂 | 模型重、N 较大 |

无论 A/B，隔离契约相同：**共享的只有不可变权重/只读技能图；所有可变状态都必须有明确的 owner 与 lifetime。**

### 2.2 胶囊清单（示例）

| 胶囊 | owner | lifetime | 复位 | 指纹 |
|---|---|---|---|---|
| `policy_weights` | shared-immutable | process | 不复位 | 权重哈希 |
| `kv_cache` | port | episode | 清空 | 块表哈希 |
| `history_stack` | port | episode | 清空 | 帧 ID 序列哈希 |
| `action_buffer` | port | episode | 清空 | 缓冲摘要 |
| `rng` | port | episode | `PRF(seed,p,ep)` | 种子+计数器 |
| `real_ledger` | episode | episode | 清空 | 事件 Merkle 根 |
| `sim_shadow` | oracle | episode | 重建 env | env 状态哈希 |
| `skill_router` | port | episode | 清空路由缓存 | 路由向量哈希 |
| `spec_cache` | port | episode | 失效 | key 集合哈希 |

**硬规则**：

1. `oracle` 胶囊对 `port/episode` 胶囊只读；任何“仿真写回策略”的代码路径直接断言失败。
2. `shared-immutable` 胶囊禁止原地更新；若需热更新，必须走“双缓冲 + 版本号”，且每端口只读。
3. 复位顺序固定；复位后必须比对黄金指纹（golden fingerprint）。
4. 每端口种子 `seed_p = PRF(master_seed, p)`，禁止共享全局 RNG。
5. 投机缓存 key 必须包含 `(port, episode_id, chunk_index)`；`reset` 时全部失效。

### 2.3 命名空间隔离（Isaac/部署侧）

| 资源 | 真机/评测 | 仿真 | 隔离手段 |
|---|---|---|---|
| DDS 域 | domain 1 | 每 env 一个域（如 101..10N） | `CYCLONEDDS_URI` / 域配置；禁止与真机同域 |
| 图像服务 | teleimager | 每 env 偏移端口 | `TELEIMAGER_CONFIG` 覆盖；检查端口占用 |
| WebRTC | 60001–60003 | 每 env 偏移 | 每 env 独立配置 |
| URDF→USD 缓存 | 不涉及 | 每版本独立目录 | 缓存 pin + 内容哈希 |
| 日志/临时文件 | 每端口独立 | 每 env 独立 | tmpdir + 端口号 |
| GPU 上下文 | — | 进程/容器隔离 | MIG 或单进程多 env |

> README 明确写了两个坑：**DDS domain 1 会与同网络真机混在一起**；**图像服务端口被占用会启动即报错**。这两条不是“理论风险”，而是 PSI 的验收项。

### 2.4 复位协议（可审计）

```python
def reset_port(p, episode_id):
    # 1) 只允许复位 port/episode 胶囊
    for c in CAPSULES:
        if c.owner in ("port", "episode") and c.lifetime == "episode":
            c.reset_fn()
    # 2) 清空投机缓存与路由缓存（必须带 port 维度）
    SPEC_CACHE.invalidate(port=p)
    # 3) 重新派生 RNG
    RNG[p] = np.random.default_rng(prf(MASTER_SEED, p, episode_id))
    # 4) 黄金指纹审计
    for c in CAPSULES:
        if c.owner in ("port", "episode") and c.lifetime == "episode":
            assert c.fingerprint() == c.golden, (c.name, "reset leak")
```

### 2.5 SILK：把“隔离”变成可证伪

| 泄漏类型 | 典型 bug | 测试 | 通过标准 |
|---|---|---|---|
| 横向·跨端口 | 共享 KV/history；全局 `reset` | T1 canary / T2 置换 / T3 kill | 输出逐位一致；canary 零命中 |
| 纵向·跨 episode | 忘清 buffer/EMA/计数 | T4 reset-fuzz + 指纹 | 复位后指纹 = 黄金值 |
| 模态·仿真↔真实 | 仿真状态写回策略/账本 | T7 只读断言 | 写入抛异常 |
| 时序·陈旧帧 | 关闭 `render_sync` 后旧图 | T5 时钟偏斜/序号校验 | 超出窗口的帧被丢弃 |
| 任务·路由串味 | 技能头/路由缓存跨任务 | T2 任务置换 | 任务输出不变 |
| 资源·端口/缓存 | 图像端口冲突、USD 缓存污染 | T6 端口扫描/缓存哈希 | 无冲突、哈希一致 |

**T1 canary 协议**：在端口 `j` 的观测中注入一个 128-bit 随机 canary（放在未使用字段或合成状态槽），监控所有端口的输出、日志、状态指纹；canary 在 `i≠j` 中出现即失败。误报概率可忽略。

**T2 置换**：固定 episode 集合，改变 episode→port 的分配；每个 episode 的输出必须只由自身输入决定，与端口号无关（种子按 episode 派生时）。

**T3 kill**：`SIGKILL` 端口 `j` 的进程/协程；端口 `i` 的剩余输出必须与无故障运行逐位一致；延迟不得出现跨端口相关。

**T4 reset-fuzz**：在推理前/中/后随机 `reset`；复位后输出必须等于从 `s_0` 冷启动的输出；账本 Merkle 根必须等于空根。

**T5 时钟偏斜**：乱序时间戳、重复帧、陈旧帧；策略必须按序号而非到达时间消费；超出窗口的帧丢弃并记录。

**T6 资源冲突**：并发启动 N 个 Isaac env；断言 DDS 域互异、图像端口互异、缓存哈希一致；用 canary 检查跨 env 串味。

**T7 只读断言**：在 `sim_shadow` 写入 `real_ledger` 的接口上抛异常；CI 中静态检查 + 运行时断言双保险。

**T8 负载**：N 端口满并发，测 P50/P95/P99 延迟、动作异常率、跨端口延迟相关性；目标 `L_out≈0`、P95 抖动在预算内。

### 2.6 与可信度的关系

README §6 明说可信度会看“逐步延迟及其波动 + 动作统计规律性”。状态泄漏的典型症状正是：某些端口延迟莫名升高、动作分布随其他端口负载变化、`reset` 后出现异常动作。**SILK 的通过标准不仅是正确性，也是可信度。** 这是把“工程卫生”转成“比赛得分”的关键。

## 3. Isaac Lab 双保真神谕：UIP-11′ ILO

### 3.1 三个角色（按价值排序）

|---|---|---|---|
| **R1 · 全服务器回放** | 用 Isaac 的 DDS/teleimager 接口驱动真实提交服务器，跑 N 端口、token、形状、延迟 | 与真机同构的通信 + 图像服务；能测到“模型之外”的失败 | 拒绝率、端到端延迟、跨端口隔离报告 |
| **R2 · 步骤分神谕** | 回放/rollout 后读 `get_step_reward_value`，对齐计分步 | 官方离散任务奖励，免手写全部谓词 | 每任务步骤分代理 |
| **R3 · 反事实实验室** | 回放真实轨迹 + 改光照/相机 + 注入扰动 | 可重渲染、可回放、可脚本化干扰 | 视觉扩增数据、恢复三元组 |

### 3.2 Sim→Submission 桥（SSB）

把 Isaac 的传感器/状态映射成提交接口的 `obs`，把 `action` 写回 DDS：

| 提交键 | Isaac 来源 |
|---|---|
| `observation.images.cam_left_high` / `cam_right_high` | 头部双目 1280×480 左右切分（各 640×480） |
| `observation.images.cam_left_wrist` / `cam_right_wrist` | 左右腕相机（teleimager 55556/55557） |
| `observation.state.left_arm` / `right_arm` | DDS `rt/lowstate` 手臂关节 |
| `observation.state.left_gripper` / `right_gripper` | Dex1 低层状态 |
| `observation.state.lower_body` | DDS `rt/lowstate` 下半身 |
| `observation.state.*_ee_pose_gripper_base` | 关节状态正运动学（FK） |
| `observation.language` | 任务字符串 |
| `action.*` | DDS `rt/lowcmd` / Dex1 目标 |
| `meta.token` | 提交 token（桥只检查，不记录明文） |

**关键点**：这让“策略 + 服务端 + 端口 + 块形状 + 延迟”走同一条真实代码路径，而不是在 notebook 里假装评测。它能在上线前抓住：块形状错误、token 漏传、obs 键缺失、端口数不匹配、某端口 `reset` 未清状态。

### 3.3 保真阶梯（不把仿真当绝对裁判）

| 层 | 代理 | 成本 | 可证明 | 不可证明 |
|---|---|---|---|---|
| L0 | 几何/规则谓词 | 极低 | 结构、顺序、撤回 | 视觉泛化、接触力 |
| L1 | Gazebo 物理 | 低 | 关节/碰撞/粗接触 | 真实外观、细接触 |
| L2 | Isaac Lab | 中高 | 接口一致性、离散步骤奖励、视觉多样性 | 绝对成功率、真实摩擦/形变 |
| L3 | 真机锚点 | 最高 | 真实成败、真实步骤分 | 大规模覆盖（样本少） |

**规则**：L2 只用于**相对排序**与**结构/接口回归**；L0/L1/L2 的绝对分数不得写成“真机结论”。所有对外结论标注代理层与 `ρ_L`。

### 3.4 风险与边界

- **场景覆盖是瓶颈**：仓库只有 5 类任务场景；32 任务需要“原型 + 资产替换”，不是“每任务一个手工场景”。
- **视觉更真 ≠ 接触更真**：不要因为渲染 photoreal 就相信插拔/折叠/拧动。
- **异步渲染**：`--render_sync` 关闭时图像可能落后一帧；验证器必须按序号对齐，否则会把“旧帧”误判为 `regressed`。
- **DDS/端口**：见 §2.3；这是隔离验收项，不是可选优化。
- **版本漂移**：Isaac Sim/Lab 版本、USD 资产、URDF 缓存都要 pin；否则“同一实验”不可复现。

## 4. 真实回放→仿真视觉扩增：UIP-16 R2S-VX

### 4.1 核心思想

常规域随机化是“**仿真动力学 + 仿真视觉**”，会同时引入动力学 gap 与视觉 gap。R2S-VX 反过来：

```text
真实数据提供：动作 a_t、机器人状态 q_t、语言、任务标签、接触语义
仿真提供：    光照、相机、背景、材质、遮挡 —— 只改“看起来怎样”
```

即 **“真实动力学 + 仿真视觉”**。它不是“用仿真造新任务”，而是“**用仿真给真实演示换更多视角**”。

### 4.2 三种模式（按可行性递进）

| 模式 | 回放对象 | 适用 | 风险 |
|---|---|---|---|
| **S · 静态重打光** | 机器人按 `q_t` 运动；物体静止或已知位姿 | 相机/光照/背景轴 | 物体运动任务不适用 |
| **R · 运动学回放** | 机器人 + 物体都用真实/跟踪位姿 | 抓放、堆叠、开合等 | 需要 6D 位姿跟踪 |
| **D · 动力学回放** | 机器人按 `q_t`，物体由仿真物理驱动 | 物体简单、接触少 | 有 sim-to-real 动力学 gap |

优先 S（最稳），其次 R（最有价值），D 只作补充。

### 4.3 管线

```python
def r2s_vx(traj, scene, renderer, n_views, mode="S"):
    # traj: {q_t, a_t, cam_images, language, labels}
    for k in range(n_views):
        delta = sample_visual_delta(          # 只采样视觉状态
            light=HDR_LIGHTS, camera=CAM_JITTER, background=BG_TEXTURES)
        for t in range(len(traj)):
            if mode == "S":
                renderer.set_robot_qpos(traj.q[t])
                renderer.set_objects(scene.static_objects)
            elif mode == "R":
                renderer.set_robot_qpos(traj.q[t])
                renderer.set_objects(traj.object_poses[t])   # 6D 跟踪
            elif mode == "D":
                renderer.set_robot_qpos(traj.q[t])
                renderer.step_objects(traj.a[t])              # 仿真物理
            img = renderer.render(delta, cameras=traj.cameras)
            yield Sample(obs=img, action=traj.a[t], language=traj.language,
                         label=traj.labels[t],
                         meta={"source": "real", "view": k, "mode": mode,
                               "delta": redact(delta)})
```

### 4.4 为什么它能提升泛化，而不只是“更多数据”

- **标签保真**：动作/状态/标签来自真实演示，不存在“仿真策略在仿真里成功”的循环论证。
- **视觉轴定向**：背景/光照/相机正是公开数据里最难覆盖、而 Isaac 最容易改的轴（README 的 `--modify_light` / `--modify_camera`）。
- **一致性约束**：同一 `(q_t, a_t)` 的多个视图共享标签，可加“视图一致性”损失，逼编码器忽略光照/背景、保留任务相关特征。

### 4.5 风险与降级

- **物体位姿是命门**：R 模式依赖 6D 跟踪/场景重建；遮挡、透明/反光物体、快速运动都会失败。
- **降级策略**：跟踪失败率 > 50% 的任务退回 S 模式（只改相机/光照）；仍不行则退回 D 模式或纯真实数据。
- **校准**：用真机留出的背景/光照位移集做 `ρ` 检验；若 R2S-VX 不优于纯真实数据，立即停止扩张。

## 5. Isaac 反事实扰动-恢复工厂：UIP-17 ICDR

### 5.1 干扰算子（从 `info.json.generalization.human_*` 编译）

| 算子 | 语义 | 例子 |
|---|---|---|
| `REVERSE` | 反向执行已完成动作 | 合上→打开、拉上→拉开、拧紧→拧回、叠好→翻开 |
| `REMOVE` | 拿走关键物体 | 中途把锁拿走 |
| `MOVE` | 移动物体/底座/插口 | 抓取前移动底座、插口移开 |
| `REINSERT` | 把已放入物放回起点 | 把货放回传送带起点 |
| `REPLACE` | 换成未见物体 | 缺失红杯、换塑料架 |

每个任务从 `human_*` 文本编译出一个**扰动程序**：

```text
P = {(operator, trigger_time ~ U[t_min,t_max], magnitude ~ U[0,1],
      duration ~ U[d_min,d_max], hand_pose ~ scripted)}
```

### 5.2 三元组生成

```python
def icdr(task, human_spec, policy, recovery, n_episodes):
    scene = load_task_scene(task)
    for ep in range(n_episodes):
        init = sample_initial_state(scene, seed=prf(EP_SEED, ep))
        trace = rollout(policy, scene, init)             # 正常轨迹
        t_d = sample_trigger(human_spec)                 # 扰动时刻
        snap = scene.snapshot()                          # 隔离快照
        disturbed = apply_operator(scene, trace, t_d, human_spec)
        rec = rollout(recovery, scene, disturbed.state)  # 恢复轨迹
        label = derive_labels(trace, disturbed, rec)     # regressed/recovered
        yield Triple(pre=snap, disturbed=disturbed, rec=rec, label=label)
```

产出：

- **正例**：`(干扰前 → 撤回 → 恢复)`，训练 `regressed` 检测与恢复；
- **负例**：施加了扰动但进度未变（如移动了一个无关物体），用于压低误报；
- **边界例**：扰动后部分恢复、恢复失败、二次撤回。

### 5.3 与 v2 DRF 的差异

- v2 用 Gazebo 脚本化机械手；本轮用 Isaac 的资产/光照/相机与更细的接触，并可把 `human_*` 文本编译成算子。
- v2 只造“干扰”，本轮显式造**负例与边界例**，直接优化 `regressed` 的误报率（这是 TSI-V 的最大风险）。
- 所有 episode 在独立 env 中运行，快照不可变；扰动 RNG 按 episode 派生，保证可复现。

### 5.4 风险

- **仿真干扰 ≠ 真人干扰**：时机、速度、力度、手部遮挡都不同。用时机/速度/位姿随机化 + 真机少量锚点校准；不要把 ICDR 的恢复成功率当成真机结论。
- **物理不可逆**：某些真实撤回（撕开、洒出）在仿真里不可逆；这些任务只做“检测”不做“恢复”训练。

## 6. 其余清单的 v3 调整

### 6.1 UIP-02′ SSG（计分步安全网）

保留。新增两条：

- 计分步与 TSI-V 的 `g` 一一对齐；`advance` 只能在真实账本 `done(g)` 后发生。
- 末步分值更高 ⇒ 在 `g` 接近末步时，CSG 收紧重做预算，优先“保前置分”，避免为搏末步把已得步骤分弄丢。

### 6.2 UIP-05 LCAG（语言→可供性）

保留。与 R2S-VX 配合：语言条件化“哪些视觉变化与任务无关”，帮助编码器在背景/光照扩增下保持稳定；不引入运行时外部 LLM。

### 6.3 UIP-09″ DCR-R（恢复执行器）

从“同手重做”扩展为四种原语：

```text
redo(g)      : 重新执行子目标 g
guard(g-1)   : 先稳住已完成的 g-1，再处理 g
reverify(g)  : 只做核验动作（靠近/触碰/观测），不改变状态
present(g)   : 把物体移到可观测/可操作位（用于被拿走/遮挡）
```

由 TSI-V 的判定与 CSG 预算选择；每次只允许一个原语，避免“边重做边改目标”的混乱。

### 6.4 UIP-13′ ACS（修正版）

- `T_a` 全局固定：按任务组合选择；接触密集任务优先小 `T_a`。
- **块内安全设计**：块尾 `hold/retreat`，保证下个块边界可纠错。
- **投机计算**：在块执行期间预计算下一块候选，但按端口隔离缓存；`reset` 立即失效。
- **延迟平滑**：预计算只用于隐藏计算，不改变返回形状；禁止返回“预测动作”冒充观测后的动作。

### 6.5 UIP-14 MSGR（模块化技能图）

- 技能图是**只读共享结构**；每端口的“当前节点、历史、路由缓存”是独立胶囊。
- 单骨干 + 参数高效技能头；技能头权重只读，禁止按端口微调。
- 软路由 + 通用回退头；路由置信度低于阈值时不切换技能，避免跨任务污染。

### 6.6 UIP-15 CSG（可信度安全阀）

- 给 `redo/reverify/guard` 设延迟预算、抖动上限、最大次数、最小间隔。
- 动作形态平滑：块尾减速/保持，避免统计规律性异常。
- 与 SILK 联动：若某端口延迟抖动超预算，降级到“保守策略 + 更小 `T_a` 的等价行为”（通过更保守的动作实现，不改 `T_a`）。

## 8. 证伪与止损（Kill Criteria）

| 如果观察到 | 说明 | 行动 |
|---|---|---|
| 共享状态在 N=3 下 `L_out≈0` 且无 canary 命中 | 隔离风险在本设置下不显著 | 降低 PSI 优先级，保留 SILK 回归测试即可 |
| ILO 校准后 `ρ_L2 < 0.4` | 仿真步骤分不能排序 | 只把 ILO 当接口/结构测试，不用于选策略 |
| R2S-VX 物体跟踪失败率 > 50% | R 模式不可用 | 退回 S/D 模式，或放弃视觉轴扩张 |
| TSI-V 去掉仿真影子后步骤分不降 | 影子无边际价值 | 把仿真影子移出控制路径，仅离线诊断 |
| 加入 ICDR 负例后误报仍高 | 扰动标签/谓词有问题 | 先修标签与谓词，不扩数据量 |
| 块边界 `T_a` 太大导致撤回检测过晚 | 反应性不足 | 全局减小 `T_a`；或把高接触任务排除在“搏末步”策略外 |

> 这些止损条件必须在立项时写进实验记录；否则“仿真越搭越大、结论越来越软”。

## 9. 合规与风险

- **运行时红线**：提交时不得调用 Isaac、Gazebo、外部 VLM/LLM、网络服务；所有仿真/数据工厂只在离线使用。`get_action` 的输入域只含接口键。
- **单模型多任务**：共享一条骨干；验证器/技能头/恢复头都是主骨干的蒸馏头或规则模块，不是独立大模型。技能图是只读结构，不是“多模型路由”。
- **不伪造真机结论**：所有 ILO/R2S-VX/ICDR 结果标注 `L0/L1/L2` 与 `ρ`；对外只声称“代理/相对排序”。
- **数据合规**：不修改官方数据集；合成数据显式标注 `source=sim/real2sim`；不把合成数据冒充真实演示。
- **仿真安全**：Isaac 使用独立 DDS 域与端口，避免与同网络真机串扰；这是安全要求，不只是隔离要求。
- **端口契约**：端口数恰等于 N；不额外暴露端口；token 不写入日志；每端口独立完成流程。
- **可信度**：延迟预算、动作平滑、异常监控；不为压延迟而返回形状不一致/统计异常的动作。
- **未取到的手册**：5 轴中的位置/干扰物/背景、评测轮次/时限/控制频率仍需飞书手册公开后核实；本轮只对已能核实的接口与仿真事实下结论。

## 11. 本轮最大风险 & 押注

**一句话最大风险**：把 Isaac 当成“更高保真的裁判”、把状态隔离当成“加锁 + `reset()`”，会同时招致 sim-to-real 自欺与多端口泄漏；真正的护城河是“三账本对账 + 隔离契约 + 真机锚点”，而不是仿真分辨率。

**→ 本轮最值得押注**：**UIP-01″ TSI-V × UIP-18 SILK × UIP-11′ ILO** 组成的“三域隔离验证 + 隔离契约测试 + 接口同构回放”，由 **UIP-16 R2S-VX** 提供“真实动力学 + 仿真视觉”的数据引擎、**UIP-17 ICDR** 提供撤回恢复数据。它精确对准两件规则/README 已写明、而大多数队伍会做错的事：**撤回必须可证明，N 端口状态必须真隔离**；且全部落在选手的离线算力与 API 权限之内。
