（研究循环·新灵感二元组第 1 轮；本轮灵感：「推理延迟」×「工具调用」）

> **基线**：第 2 轮产出 MetricVoiceGauge-NCD-HUTDH-v22+IP-431–435（HDL/ACSC/DCSC/HPC-E/CFC++），其上承 v21 语义-规范层（SDC/CAC/DCL/GIC）、v20 联邦感知证书（PCA/CTS/CFC/HPC/CFCtrl）、v19（DCM/OGCC/CCV/DRS/OGC）与 v17 感知链（CLP/S2C/HCG/PSV/APS/AMC）。
> 本轮纪律：**不推倒 v22，一个模块都不删**。本轮只做一件事：给整套证书体系补上它一直缺失的两个自由度——**「证书什么时候还可信」（时间）**与**「证书是哪个工具、以多长延迟、凭什么出处算出来的」（出处）**。即把「空间上成立的证书」升级为「时空-出处上可审计的证书」。

## 0. 直觉与动机

**灵感 1（推理延迟 → 证书是有保质期的，慢推理只该损失活性、不该损失安全）**
直觉：v20–v22 的证书几乎全是「空间谓词」：几何安全、语义证据、义务合规、能量可行。可真实世界里没有任何证书是永恒的——人在走、门在动、杯子在被拿开。证书一旦签发就开始**陈旧**，而控制环执行动作发生在签发之后（time-of-check → time-of-use 的缝隙）。更麻烦的是，产生证书的推理并不快：感知网络、合规规则、意图识别、能量核算单次 100–300ms，复合链更长。关键反直觉点：**「推理够快才安全」是个错误命题**。只要架构上允许「算不完就用保守默认」，推理延迟就只影响**活性/最优性**，不影响**安全性**——安全性由「硬截止 + 保守兜底」保证。于是本轮的第一个核心概念：**新鲜度衰减证书 (Freshness-Decayed Certificate) + 任意时证书格 (Anytime Certificate Lattice)**：证书携带有效期 `[t₀, t₀+w(C)]`，`w(C)` 由受界世界动力学反推（人体典型仅约 150ms），超期即视为「未知=保守」；任意时计算的部分结果永远保守，细化过程单调地向 v22 逼近而永不越过。

**灵感 2（工具调用 → 信任边界在「票据 + 机械核验」，不在 agent 的自述）**
直觉：v22 隐含假设「证书是就地、原子、可信地产生的」，但现代机器人高层是 LLM/规划器，它并不直接断言安全，而是**调用工具**去生成证书：叫一次感知查询、跑一次合规规则、问一次意图分类、算一次能量预算。工具会慢、会挂、会被算力争用、会返回**过期缓存**、会被幻觉参数误用，甚至「两个不同名字的工具背后是同一个模型」——于是「多工具佐证」可能只是自欺。关键反直觉点：**把高层慢推理的延迟彻底移出安全关键路径**——LLM 可以任意慢，慢到超时就降级；真正的准入门是一个小而快、可机械复核的**安全内核**，它只读「工具产出的证书」而不读「agent 的结论」。于是第二个核心概念：**工具调用票据 (Tool Invocation Certificate, TIC) + 证书推导 DAG + 出处独立性**：每个叶子是一次带签名的工具调用（输入快照/输出/延迟/新鲜窗/backend_id/契约版本），证书的可靠性 = 所有叶子时效与出处独立性的 AND；缓存只在新鲜窗内可复用，投机调用只降延迟、永不授予许可。

**三者如何统一（v23 = 时空-出处证书层）**
统一为 **v22 之上的时空-出处证书层 (Spatiotemporal-Provenance Certificate Layer, SPCL)**：TIC 记录「谁在何时用什么工具算了什么、花了多久」，新鲜度代数给出「此刻这张证书还值不值得信」，任意时格给出「预算烧完时退到哪一级仍安全」，截止调度器决定「有限的延迟预算分给哪些工具、谁可被牺牲」。统一准入门升级为 **HPC-T = HPC-E ∧ TemporalValid(C) ∧ ProvenanceSound(C)**：几何∧规范∧负信息∧能量∧**时效**∧**出处** 六者齐备才进入执行；缺任一维即退回 v22 的保守收缩，再退 v21/v20。整套设计的骨架命题只有一句：**安全由硬截止与保守兜底保证，活性才由推理速度决定**；因此 `Exec_v23 ⊆ Exec_v22 ⊆ … ⊆ Exec_v18` 闭环不破。

## 1. 研究问题（轮次升级版）

- **Q12（时空证书的时间健全性）**：如何由受界世界动力学（`v_max, a_max`）严格导出证书有效期 `w(C)`，使「证书在 `[t₀, t₀+w]` 内断言的安全」在任意动作执行时刻仍成立？当计划时域 `H > w(C)` 时，如何把计划切成需要中途「刷新证书」的分段，并证明分段刷新不引入假自由空间？`v_max` 被非合作快速个体（奔跑儿童、驶入的轮椅）违反时如何失效安全？

- **Q13（慢思考/快反射的解耦）**：如何把 LLM/规划器的任意延迟隔离在安全关键路径之外，使「高层推理超时」只触发活性降级而不影响准入？安全内核的 `O(1)` 状态查询与机械证书复核如何与 v17 APS 新鲜度阶梯、v22 分层过滤器链衔接？

- **Q14（工具调用 DAG 的截止调度与退化）**：给定证书推导 DAG 与安全截止 `D_safe`，如何按关键路径（而非简单求和）分配延迟预算、以 EDF + 关键性优先级调度，并保证可选工具（高门槛许可）可被牺牲、关键工具（STOP/几何）永不被抢占？硬看门狗与统计式 p99 截止在什么条件下等价、什么时候必须用硬截止？

- **Q15（出处独立性与投机/缓存）**：如何用 `backend_id` 与推导 DAG 定义「真正独立的证据」，使 CFC+++ 的模态/工具多样性不被「同一后端多别名」欺骗？缓存复用与投机预取在新鲜窗内如何形式化为「只降延迟、不扩权限」？工具契约（能力令牌、参数约束、输出 schema 校验）如何防止幻觉参数把不安全调用伪装成合法调用？

- **Q16（可审计重放）**：TIC 与证书 DAG 如何做哈希链式记录，使任意一次准入可在离线确定性重放（同输入 → 同判定），并支持「事后追责：哪张过期/越权票据导致了这次放行」？

## 2. 设计原则（在 P34–P37 / P41–P42 基础上新增 P43–P46）

**P43 时间健全律（Temporal Soundness）**
每张证书 `C` 携带有效期 `[t₀, t₀+w(C)]`，`w(C) = min_{leaf∈leaves(C)} w_leaf`，`w_leaf` 由该叶子所受界的世界动力学反推。仅当 `t_use + τ_exec ≤ t₀ + w(C)` 时才允许据此执行；否则证书**陈旧=未知**，必须保守化（退回未赎回的自由空间）。AND 复合取 min，OR 复合要求每条被引用的证据各自有效。故「时间」是证书真值的一部分，而非元数据。

**P44 任意时单调律（Anytime Monotonicity）**
证书细化构成单调格 `A_STOP ⊆ A_v18 ⊆ A_v19 ⊆ A_v20 ⊆ A_v21 ⊆ A_v22`；任意时计算在预算耗尽时返回当前已证的最高等级，部分结果永远**保守**。增加延迟只会把可达集合向 v22 最优单调地扩大，**永不越过 v22**。故推理延迟只影响活性，不影响安全：`SafeResult(budget) ⊆ Exec_v22` 对任意 budget 成立。

**P45 截止有界执行律（Deadline-Bounded Execution）**
控制环**永不阻塞**在工具调用上；每个工具调用带硬看门狗截止 `D_i`，超时即以保守默认返回。延迟预算按推导 DAG 的**关键路径**（`CP = max_π Σ L_i`）而非顶点和分配；关键工具（STOP/几何/负信息）不可被可选工具（高门槛许可、投机预取）抢占；统计式 p99 仅用于规划，实际执行一律硬截止。

**P46 出处独立律（Provenance Independence）**
每个证书叶子是一张 TIC，含 `backend_id / 契约版本 / 输入快照哈希 / 输出 / 延迟 / 新鲜窗`。证据或共识的「独立」以**不同 backend_id 且均在各自新鲜窗内**为准；同一 backend 的多别名不算独立。缓存复用仅在 `age ≤ w_leaf` 内合法；投机预取（speculative prefetch）只可提前计算、不得单独授予许可，必须经正式新鲜校验后方可入账。故 `Exec_v23 = Exec_v22 ∩ TemporalValid ∩ ProvenanceSound ⊆ Exec_v22`。

## 3. 与基线的接口（如何退化）

- TIC 失效（工具无票据/票据不可验签）⇒ 该工具产出视为不可信 ⇒ 相关证书降为「未证」，退回 v22 的保守收缩；
- 新鲜度失效（`t_use > t₀+w(C)`）⇒ 证书陈旧 ⇒ 未赎回自由空间重新封闭 ⇒ 等价或更保守于 v22；
- 任意时预算耗尽 ⇒ 返回 `A_STOP`/`A_v18` 等保守等级 ⇒ 子集，活性单调下降；
- 调度器失效（看门狗失灵）⇒ 进入**最大限制模式**（控制环只允许 `A_STOP` 的静态安全动作）⇒ `Exec_v23 ⊆ Exec_v22` 仍成立；
- 出处独立性不满足（仅单后端可用）⇒ 共识退回 v22 的 CFC++ 行为 ⇒ 等价 v22；
- 投机/缓存失效 ⇒ 丢弃预取、强制重算或保守化，绝不扩权；
- 全失效 ⇒ 完全回退 v22 ⇒ `Exec_v23 ⊆ Exec_v22 ⊆ Exec_v21 ⊆ Exec_v20 ⊆ … ⊆ Exec_v18`（引理 166）。
- **安全继承的方向性**：时间失效向保守、出处失效向保守、预算耗尽向保守、看门狗失效向保守——任意单点故障只使执行集合收缩，不使其扩张。慢推理的安全代价被结构性归零。

## 4. 预期贡献

1. **时空证书**：首次把「有效期」形式化为证书真值的一部分，给出由受界世界动力学导出的保质期公式（人体典型 ~150ms），把 v17 的新鲜度概念从感知层升级为全证书体系的一等维度；
2. **慢思考/快反射解耦**：证明「推理延迟与安全性正交」——任意慢的 LLM 规划器都不能通过「拖慢」制造不安全执行，安全只由硬截止 + 保守兜底 + 机械复核保证；
3. **工具调用票据与推导 DAG**：把每次工具调用变成可审计、可重放、带出处与延迟的票据，证书可靠性 = 叶子时效与出处独立性的 AND；
4. **截止预算调度**：给出 DAG 关键路径预算分配 + EDF/关键性调度 + 硬看门狗，明确「可牺牲可选工具、不可牺牲关键工具」的降级语义；
5. **投机与缓存的保守语义**：缓存仅在新鲜窗内复用、投机只降延迟不扩权限，给出「预取不破坏安全继承」的证明；
6. **HPC-T 六证一体**：`HPC-E ∧ TemporalValid ∧ ProvenanceSound` 统一准入门，`Exec_v23 ⊆ Exec_v22` 闭环，且任意单点故障向保守退化。

## 5. 本轮最大风险

**一句话**：整套「慢推理不影响安全」的论证依赖一个未加证明的前提——**安全内核读取的底层快照（位姿/点云/时间戳）本身是新鲜的**；若最底层的感知/位姿工具恰在算力争用时被重尾延迟拖慢，硬看门狗只能保证「不阻塞」，却无法保证「快照没过期」，于是内核会在一个已经过时的世界里签发「时间健全」的证书，形成 TOCTOU 漏洞——即「合格的时效检查，检查的是一张过期的世界」。

## 1. 严格推导

### 1.1 新鲜窗（保质期）的导出

设某叶票据在 `t₀` 时刻断言：目标区域 `R` 内无相对距离小于 `m_req` 的障碍。被跟踪对象的速度 `≤ v_max`、加速度 `≤ a_max`。到 `t₀+Δ` 时，该对象相对 `R` 的位移最大为

```
d(Δ) = v_max·Δ + ½·a_max·Δ²      （保守：取持续同向加速的最坏情形）
```

要求证书在动作执行完毕前仍成立，即 `d(Δ) ≤ m_req` 且 `Δ ≥ τ_exec`。解 `d(Δ)=m_req`：

```
Δ* = ( sqrt(v_max² + 2·a_max·m_req) − v_max ) / a_max
w_leaf = max(0, Δ* − τ_exec)
```

**数值实例**（人体常态）：`v_max = 1.5 m/s, a_max = 2.0 m/s², m_req = 0.25 m, τ_exec = 0.02 s`：

```
Δ* = ( sqrt(2.25 + 1.0) − 1.5 ) / 2.0 = (1.8028 − 1.5)/2.0 ≈ 0.1514 s
w_leaf ≈ 0.131 s
```

结论：**人体场景的新鲜窗约 130–150 ms，小于典型 100–300 ms 的单次深度推理延迟**。这不是工程噪声，而是「证书在签发时也许成立、在执行时已经过期」的结构性事实——正是本轮必须引入时间维度的定量理由。各证书取 `w(C) = min_{leaf} w_leaf`。

### 1.2 计划时域超过新鲜窗：分段刷新

若计划时域 `H > w(C)`，把 `[0,H]` 切成 `n = ⌈H/w⌉` 段，第 `k` 段在 `tₖ = k·w` 之前必须拿到**新的**有效证书。令 `Ξ(π) = ∧_k TemporalValid(C_k, tₖ)`。则

```
Ξ(π) ⇒ C 在整个执行期成立（归纳：每段内 <w，段边界重刷新）
```

且每段刷新只可能**重新封闭**未被新证据赎回的自由空间，绝不扩大——因为 `A_g` 单调嵌套。故分段刷新不引入假自由空间。

### 1.3 主引理（延迟与安全正交）

**引理 164（延迟不变性）**：对任意推理预算 `B`、任意工具延迟分布（含重尾）及任意超时策略，若准入只经 `HPC-T` 机械复核且看门狗硬截止生效，则实际执行的计划集合满足 `Exec(B) ⊆ Exec_v22`。

*证明要点*：`HPC-T = HPC-E ∧ TemporalValid ∧ ProvenanceSound`。`HPC-E` 已保证 `⊆ Exec_v22`（v22 归纳假设）。任意时格在任何预算下返回某 `A_g`，`A_g ⊆ A_v22`（P44）。超时以保守默认返回，只可能使 `grade` 下降（P45）。`TemporalValid`/`ProvenanceSound` 不通过时一律保守化（P43、P46）。四条路径全是收缩，故结论成立。∎ —— 即安全与延迟**正交**，延迟只改变 `|Exec(B)|`（活性）。

**引理 165（投机安全）**：投机预取证书 `spec(C')` 不能单独授予许可；它只有在被正式新鲜校验（`TemporalValid ∧ ProvenanceSound`）通过后才可转正，且转正判定与「不预取直接计算」逐位一致。*由 P46 与 DAG 哈希定值直接得。*

**引理 166（退化链）**：`Exec_v23 ⊆ Exec_v22 ⊆ Exec_v21 ⊆ Exec_v20 ⊆ … ⊆ Exec_v18`。*逐层交集 + 任意单点故障向保守退化得证。*

### 1.4 截止调度

证书 DAG 的端到端时延不是顶点延迟之和，而是**关键路径**：

```
CP(G_C) = max_{path∈G_C} Σ_{v∈path} L_v
```

并行工具（不同分支）可隐藏延迟；串联工具（依赖链）放大延迟。准入可行条件：

```
可行 ⇔ CP(G_C) ≤ D_safe  且  看门狗为硬截止（非 p99）
```

预算不足时按「关键性」裁剪：可选工具（高门槛许可 `P`、投机预取）先降级；关键工具（STOP、几何 HPC、负信息 AbsCert）永不被抢占。

## 2. 关键算法骨架

```python
import time, hashlib
from dataclasses import dataclass, field
from typing import Callable, Any

# ---------- IP-436 Tool Invocation Certificate ----------
@dataclass(frozen=True)
class TIC:
    tool: str
    backend_id: str            # 出处：同模型多别名必须相同
    contract_ver: str
    x_in_hash: str
    y_out: Any
    t_start: float
    t_end: float
    w: float                   # 新鲜窗（秒），由 FDCA.freshness 给出
    deps: tuple = ()           # 依赖的上游 TIC 哈希
    sig: str = ""

    @property
    def latency(self): return self.t_end - self.t_start

    def age(self, t): return t - self.t_end

    def temporal_valid(self, t):
        return self.age(t) <= self.w

    def digest(self):
        return hashlib.sha256(
            f"{self.tool}|{self.backend_id}|{self.contract_ver}|"
            f"{self.x_in_hash}|{self.t_end:.6f}|{self.w:.6f}|{self.deps}".encode()
        ).hexdigest()


# ---------- IP-437 Freshness-Decayed Certificate Algebra ----------
class FDCA:
    def __init__(self, v_max, a_max, margin_req, tau_exec):
        self.v_max, self.a_max = v_max, a_max
        self.margin_req, self.tau_exec = margin_req, tau_exec

    def freshness(self):
        import math
        d_star = (math.sqrt(self.v_max**2 + 2*self.a_max*self.margin_req)
                  - self.v_max) / self.a_max
        return max(0.0, d_star - self.tau_exec)

    def compose_and(self, tics):          # 合取：最弱环
        return min((tic.w for tic in tics), default=0.0)

    def compose_or(self, branches):       # 析取：各支须各自有效，取被采用支
        return min(b.w for b in branches if b.selected)

    def temporal_valid(self, tics, t_now):
        return all(tic.temporal_valid(t_now) for tic in tics)


# ---------- IP-438 Anytime Certificate Lattice ----------
GRADES = ["STOP", "v18", "v19", "v20", "v21", "v22"]   # 单调：越靠后越大

class AnytimeRefiner:
    """在预算 B 内尽量上升到最高 grade；耗尽则返回当前已证 grade。"""
    def refine(self, cert, budget, checks):
        best = "STOP"
        deadline = time.monotonic() + budget
        for grade, check in checks:              # 由低到高
            if time.monotonic() > deadline:
                break
            if check(cert):                      # 机械复核，O(1)/O(log n)
                best = grade
            else:
                break                            # 单调：上级不成立则停止
        return best

    def allowed_set(self, grade):
        return ALLOWED[grade]                     # 恒 ⊆ ALLOWED["v22"]


# ---------- IP-439 Deadline-Budgeted Tool Scheduler ----------
class DBTS:
    def __init__(self, d_safe):
        self.d_safe = d_safe

    def critical_path(self, dag):                 # PlainDAG: {node: [preds]}
        best = {}
        for v in topo_order(dag):
            best[v] = dag.node[v].p95_latency + max(
                (best[p] for p in dag.node[v].preds), default=0.0)
        return max(best.values())

    def schedule(self, dag):
        cp = self.critical_path(dag)
        if cp > self.d_safe:
            # 先牺牲可选工具（许可/投机），关键工具保留
            dag = self._drop_optional(dag)
            cp = self.critical_path(dag)
            if cp > self.d_safe:
                return None, "DEADLINE_INFEASIBLE"   # 保守：只留 STOP
        return execute_edf(dag, hard_deadline=self.d_safe), "OK"


# ---------- 安全内核：小而快、只读证书、不读 agent 结论 ----------
class SafetyKernel:
    def __init__(self, fdca, dag_builder, refiner, scheduler):
        self.fdca, self.dag_builder = fdca, dag_builder
        self.refiner, self.scheduler = refiner, scheduler

    def admit(self, plan, budget):
        dag = self.dag_builder(plan)
        order, status = self.scheduler.schedule(dag)
        if order is None:
            return "STOP", None                    # 不阻塞，立即保守
        try:
            tics = run_with_watchdog(order, budget)  # 硬看门狗
        except TimeoutError:
            return "STOP", None
        t_now = time.monotonic()
        # 出处校验：验签 + 契约 + backend 独立
        if not all(verify_contract(t) for t in tics):
            return "STOP", None
        if not self.fdca.temporal_valid(tics, t_now):
            return "STOP", None                    # 陈旧=未知=保守
        grade = self.refiner.refine(tics, budget, ordered_checks(tics))
        return grade, tics


# ---------- IP-440 CFC+++ / Latency-Tool Consensus ----------
class LatencyToolConsensus(CertificateFederatedConsensusPlusHierarchical):
    def consensus_round(self, t_now, timeout=0.0):
        results = {}
        for key, votes in self.votes.items():
            # 1) 只收时效有效的票
            valid = [v for v in votes.values() if v.tic.temporal_valid(t_now)]
            # 2) 出处独立：backend_id 去重（不看 tool 名）
            backends = {v.tic.backend_id for v in valid}
            # 3) 投机票不计入正式共识
            formal = [v for v in valid if not v.speculative]
            count_ok = len(formal) >= self.N - self.F
            modality_ok = len({v.modality for v in formal}) >= self.M_MIN_MODALITIES
            prov_ok = len(backends) >= self.M_MIN_MODALITIES
            layer_ok = self._check_layer_consistency(formal)
            if count_ok and modality_ok and prov_ok and layer_ok:
                results[key] = self._majority_with_outlier_filter(formal)
            else:
                results[key] = "CI"               # 保守仲裁
        return results
```

## 3. 实验设计

**场景与工具 DAG。** 三类工具：`perceive`（点云+DNN，L~LogNormal，重尾，含 GC 停顿）、`comply`（规则引擎，快）、`intent`（手势 conformal，中等）、`energy`（机械臂能耗积分，中等）。证书 DAG：`perceive → (comply ∥ intent ∥ energy) → HPC-T`。人体运动用受界模型 `v≤1.5, a≤2.0`，并注入 5% 的「快速闯入者」违反 `v_max` 的对抗轨迹。

**对照。** (A) v22 原样（无时效/无票据）；(B) v23 完整；(C) v23 去时效（只留票据）；(D) v23 去出处独立（允许同 backend 多别名计票）；(E) v23 用 p99 软截止替代硬看门狗；(F) v23 开/关投机预取。

**指标。** ①**不安全执行率**（本应在任何配置下为 0，用于证伪引理 164/165）；②**陈旧使用率**（执行时所用证书已过期的比例）；③**活性**（单位时间成功准入次数 / 平均可行进距离）；④**准入尾延迟**（p50/p99/max）；⑤**TOCTOU 暴露窗口**（签发→执行完成的 `Δ` 超过 `w` 的比例）；⑥**可审计重放一致率**（重放判定与原判定逐位一致）。每个配置 ≥ 30 组随机种子，报告 bootstrap 95% 置信区间。

**预期结果（待验证，明确标注为预测）。**

| 配置 | 不安全执行率 | 陈旧使用率 | 相对活性 | 准入 p99 |
|---|---|---|---|---|
| A v22 原样 | 可能 >0（重尾时陈旧） | 高 | 1.00 | 低 |
| B v23 | 0（构造性） | ≈0 | 0.70–0.85 | 受 `D_safe` 硬约束 |
| C 去时效 | >0 | 高 | 0.90 | 低 |
| D 去出处 | 0（保守但可能误信） | ≈0 | 0.75 | 受约束 |
| E 软 p99 截止 | **>0（尾部导致）** | 低但非零 | 0.88 | 不受硬约束 |
| F 开投机 | 0 | ≈0 | 0.85–0.95 | 降低 p50 |

**判据。** 若 B 在任何种子下不安全执行率 >0，引理 164 的某假设（多半是「底层快照本身新鲜」）被违反——这正是本轮最大风险的可检验化。

## 4. 可审计重放

TIC 做哈希链：`digest = H(tool ‖ backend_id ‖ contract_ver ‖ hash(x_in) ‖ t_end ‖ w ‖ deps)`，证书 DAG 的根即整条推导的默克尔根。离线重放只需 `(TIC 集合, 复核代码版本, t_now)` 即可**确定性**复现准入判定；任何「过期票被采纳」「同 backend 多别名计票」「投机票越权转正」都能被点名为具体票据并追责。

## 5. 本轮最大风险（更新）

**一句话**：整套「慢推理与安全正交」的证明，把最底层输入（位姿/点云/时间戳）的新鲜度**当成了公理**；一旦感知这一最底层工具被算力争用拖入重尾，硬看门狗只能保证「不阻塞」而不能保证「快照没有变旧」，安全内核就会在一张过期的世界上签发「时间健全」的证书——即「合格的时效检查，检查的是一张过期的世界」；其后果不可由 p99 统计消化，只能靠**底层感知的硬实时与看门狗级联**来兜底。
