## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（开源软件 → 这不是「用开源模型」，而是「读开源规格」）**
直觉：大多数队伍把开源理解成「下载权重、跑通脚本」。但开源真正值钱的是**规格与实现**：官方仓库就是这场比赛最权威的「论文」——它写明了动作是相对 SE(3)、统计怎么合并、loader 怎么采样、server 怎么起、评测记录哪些可信度指标。三个推论：
(a) **源码考古是一等方法**：F24 的「采样按样本数、统计按等任务」不一致，只有读源码/文档才能发现，任何建模都推不出来。应建立**开源能力账本**：逐项标注「免费已有 / 已坏需 patch / 缺失 / 默认陷阱」。
(b) **组合优于发明**：starVLA、Qwen-Image、LeRobot Arrow cache、uv、flash-attn、LoRA 都是现成件；胜负手是把它们**正确组合并对齐评测规格**，不是重造 VLA。
(c) **开源发布纪律 = 隐藏分**：F21 明示评测记录时延波动与动作统计规律性并可能计入可信度。**可复现、低抖动、动作健康**本身就是分。版本化配置、run manifest、适配器热更、CI 冒烟——这些「软件工程卫生」直接映射到可信度。
核心反直觉点：**在同一份开源基线上，最大优势不是更强的模型，而是一套更可靠、更快迭代、更难出错的工程系统。**

**灵感 2（云边协同 → 不是分布式推理，而是「谁允许慢」的设计权）**
直觉：云边协同的常见误解是「把模型切开、一半放云一半放边」。在本题里真正有用的是**按关键性分层**：
(a) **同步热路径（边）**：任何在 `get_action` 内、必须在该步预算（15Hz≈66ms，F12）内完成、且行为确定的操作——观测解码/resize、VLM+DiT 前向、guard、状态机。它**绝不能阻塞等待**。
(b) **异步顾问（云）**：可以慢 100ms–数秒、结果只作「建议」的计算——世界模型前瞻（I7）、检索库查询（I9）、多样本重排、额外 VLM 推理。结果带 `(episode, step, version, deadline)`，**过期即弃**。
(c) **离线构建（云）**：训练、增广（I1）、合成示教（I5）、索引/统计构建。它们根本不进评测时延。
(d) **产物契约**：云产出的可分发物是 **LoRA 适配器（F23）+ 统计/动作掩码 + 检索索引 + 配置**；边只加载、校验版本、执行。这正是 F21「共享后端 + N 轻量端点」的架构语言。
核心反直觉点：**云边协同的价值不是更多算力，而是一条纪律——明确什么被允许慢、慢的结果如何安全地被消费。** 多数队伍要么把所有东西塞进热路径（抖动爆炸），要么什么测试时计算都不敢加；**分层边界才是设计变量。**

**二者统一**：开源回答「哪些不用自己造」（组合 + 考古 + 可复现），云边回答「哪些允许慢、如何安全消费」（关键性分层 + 产物契约）。合起来是本轮结论：**在开源基线上做一个「薄而确定」的边端运行时，把省下的工程预算投到云端的数据/顾问计算。** 这修正第 2 轮「数据引擎」论：数据引擎住在云，边端只是无聊、快速、确定的执行器；分数 ≈（数据引擎）×（边端可靠性）。

### 1.5 严谨定义（把直觉钉成可检验对象）

- **定义 1（同步热路径）**：一次 `get_action` 返回前必须完成的算子集合 `E`，其总时延 `τ_E` 直接进入评测的每步时延；要求 `p99(τ_E) < T`，`T=66.7ms`。
- **定义 2（异步顾问）**：输出可选的算子，结果附时间戳与版本，记为 `r=(payload, t_query, version, deadline)`；只在其目标控制步之前到达且状态未显著漂移时可被消费。
- **定义 3（顾问视界）**：`d = ceil(C_p99 / T)`，`C` 为顾问端到端时延；顾问实际只在第 `t+d` 步及之后生效。
- **定义 4（混合一致）**：采样任务分布 `q` 与归一化统计合并权重 `q` 相同；形式化为 `q_i = w_i n_i / Σ_j w_j n_j` 且统计用同一组 `q_i` 合并。
- **定义 5（能力账本）**：映射 `capability → (status∈{free, broken, absent, trap}, source@sha, evidence, action)`，随上游 commit 可重放校验。

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2）

> 检索日期：2026-11-26 / 11-27 / 11-28；来源见 §6。承接 v1.1：新增 I10/I11，深化 I1/I2/I5/I6/I7/I8/I9，I3/I4 维持。清单只增改不重置。本轮总纲：**薄边端 + 厚云端**——同步热路径最小化，数据/顾问计算放云端，一切跨云边产物版本化。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I1 v3 考纲校准五轴增广引擎（+ 归一化一致增广） ★★★★★
- **动机**：（v1.1 保留）计分的真机评测每次在 5 轴上偏离训练分布（P2/F2）；泛化缺口是全局乘性损失。
- **本轮深化（开源软件）**：增广不只改像素，还要改**归一化统计**。F22 规定相对动作用全局 z-score（`μ,σ` 来自训练混合），若增广把动作/位姿分布推离原统计却沿用旧 `μ,σ`，训练目标与推理反归一化会系统性偏移。因此每次增广放量后**重算全局相对动作统计与 q01/q99**；增广管线必须调用与官方完全一致的相对 SE(3)/重采样实现（见 I5 的 round-trip 测试）。
- **与现有方案差异**：盲目增广队伍只改图像、不改统计；本点把「数据分布」与「归一化空间」当成一个整体一起搬。
- **技术可行性**：高。考纲卡半自动（LLM 解析 wiki + 人工校对，约 10 分钟 × 32）；统计重算复用官方合并代码。
- **所需资源**：分割/inpainting 1×24GB GPU（官方单卡默认，F11）；磁盘同 v1.1。
- **落地步骤**：①32 张考纲卡；②背景/干扰物按考纲放量；③**每次放量后重算统计并回归 L0**；④外观/位置剂量-响应；⑤轴间交互 2 档析因。
- **风险**：统计重算的任务权重若与采样权重不一致（见 I2），会把 F24 的不一致放大；缓解：统一走 I2 的 `q_i`。

### I2 v3 数据引擎 2.0 + 混合一致共训 ★★★★★
- **动机**：单模型平均分被最弱任务支配（P1）；示教语料与质量双重浪费（P8）；**F24：采样按样本数、统计按等任务，二者混合假设互相矛盾**。
- **本轮深化（开源软件核心发现）**：在 v1.1 三件事（孪生入训 / loader 加权 patch / 示教质量加权）之上，加第 4 件——**混合一致共训**：
  1. 定义目标任务混合概率 `q_i`：32 考题全量 `1.0`、孪生 `0.5·s`、远任务 `0.05`，归一化得 `q`；
  2. **采样器**按 `q` 采样（替代官方按样本数比例）；
  3. **归一化统计**用同一 `q` 合并（替代官方等任务 `1/M`）：
     `μ = Σ_i q_i μ_i`，`σ² = Σ_i q_i(σ_i² + μ_i²) − μ²`（逐分量）；
  4. 左右臂统计先各自合并、再按官方规则合并，但组权重仍用 `q`。
  - 直觉：模型「看到什么分布」必须与 normalizer「以为是什么分布」一致；否则 `q` 偏离越大，动作解码越偏。
- **与现有方案差异**：现有队伍最多 patch 采样；本点修的是**采样-统计不一致**的根因，且给出可解析验证的公式。
- **技术可行性**：高（纯数据工程 + 单测）。
- **所需资源**：孪生子集 ≈1–2TB + 32 任务 ≈2TB；训练 1×24GB 起步、8×A100 上限。

### 1.2 混合一致共训：采样与统计同用 `q_i`（I2 v3）

```python
import numpy as np

def task_mixture(names, n_i, twins, challenge):
    w = {n: (1.0 if n in challenge else 0.5*max_sim(n, twins) if max_sim(n, twins)>0.5 else 0.05)
         for n in names}
    z = sum(w[n]*n_i[n] for n in names)
    return {n: w[n]*n_i[n]/z for n in names}          # q_i

class MixtureConsistentSampler:                        # 采样侧
    def __init__(self, q, datasets): self.q, self.ds = q, datasets
    def sample(self):
        name = np.random.choice(list(self.q), p=list(self.q.values()))
        return self.ds[name][np.random.randint(len(self.ds[name]))]

def merge_stats_with_q(stats, q):
    """stats[i] = {mu: (d,), std: (d,)}；与采样同权重合并（F22 §12 的加权推广）"""
    mu = sum(q[i]*stats[i]["mu"] for i in stats)
    var = sum(q[i]*(stats[i]["std"]**2 + stats[i]["mu"]**2) for i in stats) - mu**2
    return {"mu": mu, "std": np.sqrt(np.maximum(var, 0))}

# 单测（关键）：batch 频率≈q；merge_stats_with_q 与解析值一致；
# 当 q=1/M 时退化为官方等权公式，当 q=n_i/N 时退化为样本加权公式。
```

### 1.3 云边异步顾问调度器（I11，统一 I7/I9）

```python
import time, math

class AdvisoryScheduler:
    """边端只消费『新鲜且状态一致』的顾问；绝不阻塞热路径。"""
    def __init__(self, period=1/15, max_age_steps=2, tau_state=0.05):
        self.T, self.max_age, self.tau = period, max_age_steps, tau_state

    def submit(self, episode, step, kind, query):           # 云侧 worker 异步跑
        return self.pool.submit(self._run, episode, step, kind, query)

    def _run(self, episode, step, kind, query):
        t0 = time.time()
        payload = self.advisors[kind].infer(query)          # 世界模型/检索
        return dict(payload=payload, t_query=t0, t_done=time.time(),
                    version=self.artifact_version)

    def consume(self, res, now_step, state_delta):
        age = now_step - res["step"]
        fresh = age <= self.max_age and (time.time()-res["t_done"]) < self.max_age*self.T
        consistent = state_delta < self.tau                  # 物体/关键点漂移
        return res["payload"] if (fresh and consistent) else None   # 过期即弃
```

### 1.5 边端运行时：薄端点 + 共享后端 + 版本握手（I6 v2）

```python
class EdgeEndpoint:                         # 每端口一个；状态严格隔离
    def __init__(self, port, backend, expected_hash):
        self.port, self.backend = port, backend
        self.expected_hash = expected_hash
        self.state = {}                     # per-episode: history, reset_state, lang

    def reset(self):
        self.state.clear()
        assert self.backend.artifact_hash == self.expected_hash, "artifact drift"

    def get_action(self, obs):
        if self.state.get("episode") != obs["episode_id"]:
            self.reset(); self.state["episode"] = obs["episode_id"]
        req = self.preprocess(obs)                       # 解码/resize，边端确定
        chunk = self.backend.infer(req, timeout_ms=45)   # 共享后端，超时即降级
        if chunk is None:                                # 降级阶梯
            chunk = self.edge_fallback(obs)              # 短 chunk / 无顾问
        chunk = self.guard(chunk, obs)                   # I3/I4/I5 guard
        return self.with_token(chunk)
```

## 2. 实验设计（分级消融 + 系统门禁 + 顾问实验）

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0 | I1 剂量-响应；I2 **混合一致 vs 官方默认**；I5 合成管线 round-trip；I9 不伤标称；I11 顾问 on/off × 视界 `d` | 离线（免费） | I2：`q` 一致组 Δprog>0 且无家族退步；I11：`d=1` 净增益>0，`d≥2` 若≤0 则退回离线 |
| L1 | 2^(k-p)：增广 4 轴 × {on/off}；guard 栈 3 模块；顾问 {无/同步/异步} | 离线 + 少量真机 | 主效应显著的 ≤3 组进 L2 |
| L2 | top 组合真机：≥2 任务 × 各 2 次 | 单任务通道 | 真机增益 ≥ 离线预测 50% |
| **系统门禁** | N 端口并发；状态隔离；版本握手；p99/jitter；动作规律性 | 本地 stub + 压测 | 0 拒绝动作；p99<40ms；jitter 有界；动作界内/平滑/无离群 |
| **可复现门禁** | manifest 重放：SHA/数据/统计/adapter 全匹配 | CI | 一条命令复现同一 ckpt 与同一 L0 分数 |

**顾问视界实验（I11）**：固定任务与 ckpt，人为注入 `C ∈ {33, 66, 100, 200, 400}ms`，测 `d=ceil(C/T)` 与净增益 `g(d)`；拟合 `g(d)` 单调下降曲线，取 `g(d)>ε` 的最大 `d` 作为该节点的顾问准入上限。

## 3. 时延与 staleness 推导（严谨版）

- 控制周期 `T = 1/15 s ≈ 66.7ms`；边端计算 `τ_E`，要求 `p99(τ_E) < T`。
- 顾问端到端 `C`；顾问视界 `d = ceil(C/T)`；顾问在第 `t+d` 步最早可用。
- 消费条件：`age = t_now − t_query ≤ W`（时间窗）且 `‖x_obj(t_now) − x_obj(t_query)‖ < ε`（状态一致性）。
- 期望净增益 `Δ(d) = g(d) − λ·P(stale)`，其中 `g(d)` 随 `d` 递减、`P(stale)` 随 `d` 递增；准入当且仅当 `Δ(d) > 0`。
- 频率语义：训练 chunk `30@30fps = 1s`；部署 15Hz 下若直接执行会变成 2s。必须显式重采样（F22 §15），并在 L0 用「反归一化后物理位移」校验，而非只看张量形状（F26）。
