研究循环·新灵感二元组第 1 轮；本轮灵感：「微调」×「竞品分析」

> **基线**：第 3 轮产出 MetricVoiceGauge-NCD-HUTDH-v22 + IP-431–435（HDL/ACSC/DCSC/HPC-E/CFC++），其上承 v21 语义-规范层（SDC/CAC/DCL/GIC/HPC+/CFC+）、v20 联邦感知证书（PCA/CTS/CFC/HPC/CFCtrl）、v19（DCM/OGCC/CCV/DRS/OGC）与 v17 感知链（CLP/S2C/HCG/PSV/APS/AMC）。
> 本轮纪律：**微调改变的不是某条结论，而是产出结论的那台机器；竞品分析不是"看别人做得多好"，而是从两侧夹住系统——既向上证伪"你太乐观"，也向下证伪"你太保守"**。不推倒 v22：HDL/ACSC/DCSC/HPC-E/CFC++ 一个都不删。本轮只做一件事：**在 v22 之上加一层"自适应-竞争"证书层，把"一次标定、永久信任"升级为"每次模型更新都再认证、每个安全结论都经外部证伪、每份保守都记在活性账上"**。

## 0. 直觉与动机

**灵感 1（微调 → 证书的生产者本身可被微调，于是"可靠性的边界"会移动，而平均精度测不到这条边界）**
直觉：v22 的 DCSC/GIC/能量模型都是"一次标定、永久信任"的：DCSC 用 conformal 给出感知覆盖，GIC 用 conformal 给意图预测集，`P=f_θ` 给能耗模型。但真实部署里这些 θ 会被持续微调（新用户、新工位、新光照、领域数据回灌、对抗样本修补）。致命之处在于：**微调改变的不是某条结论，而是产出结论的那台机器**——旧 conformal 分位、旧召回下界 κ_c、旧 Lipschitz 常数在微调后全部失效，而如果监控器本身也由同源数据微调，它就会"自我感觉良好"。核心创新：**微调验收证书 (Fine-Tune Acceptance Certificate, FTAC)**——θ' 只有在**安全关键切片 S_crit** 上通过四项检验才被接纳：（i）覆盖率保持 `coverage ≥ 1-α-ε_tol`；（ii）召回下界不回退 `κ_c(θ') ≥ max(κ_c(θ), κ_req)`；（iii）输出稳定 `||f_{θ'}-f_θ|| ≤ ε_stable`；（iv）逐状态"不更乐观" `verdict_{θ'} ⊑ verdict_θ`。关键反直觉点：**验收指标不是 mAP/平均精度，而是证书在最危险那一片上的退化量；一个 mAP 涨 5% 却让儿童召回跌 2% 的微调必须被拒绝**。这把 v21 最大风险（AbsCert 押在 κ_c 经验假设上）从"部署时的一次赌博"变成"每次模型更新时的一次再证明"。

**灵感 2（微调 → 最安全的微调不是"微调整个模型"，而是"冻结会被证书读取的部分 + 只允许可证界的残差移动"）**
直觉：既然证书只读取模型的某个"安全头"（检测框置信、意图 logits、能耗预测），那就不该让微调自由改动这条读取通路。**可证残差适配 (Certified Residual Adaptation, CRA)**：冻结安全头与证书计算图，只允许低秩残差 `ΔW=BA` 在 L2 预算 `||ΔW||₂ ≤ ρ` 内移动表征；用各层 Lipschitz 常数把残差范数逐层传播成安全头输出的变化上界 `ε_stable`。关键反直觉点：**"冻结"不等于"输出不变"——被冻结的头是固定的、因而是可分析的；变化被关进一个由 ρ 与 L_f 显式可算的球里**。越界即拒绝，而不是"再训一版看看"。

**灵感 3（竞品分析 → 双义：对上是"证伪压力"，对下是"离线最优的竞争比"）**
直觉：竞品分析常被理解成"看看别人做得怎样"。但在安全证书语境里它有两个更锋利的含义，且恰好从两侧把系统夹住：
**(a) 证伪压力（adversarial）**：维护一个**竞品证伪集 (Competitor Falsification Set, CFS)**——异构感知模型、对抗策略、更强的基线规划器、人类红队。任何竞品在我们声称"覆盖区内无人"的地方检出人、或找到一个我们判为不可行却确实安全的计划，都是对我们证书的一次证伪。竞品的障碍证据**只并入不剔除**（自由空间取交，`Free=Free_self ∩ ⋂Free_c`），故 CFS 只能收缩执行域、绝不会放宽安全——**我们用竞品来"更快地失去许可"，而不是"获得许可"**。关键反直觉点：**竞品分析的目的不是取胜，而是在现实撞上来之前先被自己人证伪；最强的对手就是最好的免费红队**。
**(b) 在线竞争比（algorithmic）**：把"离线全知最优"当作另一个竞品。安全层天生保守（最极端：停机永远安全），所以真正该问的不是"够不够安全"而是"比离线最优差多少"。定义**安全-活性竞争比 (Safety-Liveness Competitive Ratio, SLCR)** `ρ_t = Cost(π_t)/Cost(π*_offline)`，把保守度按模块分解 `ρ=Π_i ρ_i` 归因到 AbsCert/DCL/EVC/CFS 各模块，并用**保守度预算分配**把总 ρ 压在 `ρ_max` 以内。关键反直觉点：**"停机"是竞争比无穷大的方案——绝对安全但零活性；好的安全层不是最安全的，而是竞争比有界的**。这正面回应 v22 最大风险（配空间能耗过度保守导致活性坍缩）。

**两者如何统一（"三明治"）**
**微调**从内部移动可靠性边界，**竞品分析**从外部提供双向证伪：CFS 从上往下压"你是否太乐观"（安全性），SLCR 从下往上顶"你是否太保守"（活性）。系统被夹在 `[ρ 下界, 证伪上界]` 之间。统一为 **v22 之上的自适应-竞争证书层 (Adaptive-Competitive Certificate Layer, ACCL)**：FTAC/CRA 管"模型更新后还能不能信"，CFS 管"外部能否推翻我们"，SLCR 管"我们的保守是否可接受"。共享状态扩展为 `ζ_accl = ζ_pgev ∪ (θ_hash, calib_hash, S_crit, ε_stable, C, ρ_budget, unfalsified)`。统一准入门升级为 **HPC-EC = (HPC-E, FTAC, Unfalsified)**：`Exec_v23 = Exec_v22(θ') ∩ Fil_ft ∩ Fil_cfs ⊆ Exec_v22(θ')`，且对安全关键切片 `Exec_v23(θ')|_{S_crit} ⊆ Exec_v22(θ)|_{S_crit}`。SLCR 不进入安全与门，它是**部署审查的活性证书**：`ρ ≤ ρ_max` 才准上线，运行时超预算触发保守度重分配而非停机。于是一侧守住"不会更乐观"，一侧守住"不会保守到停机"，安全继承与活性都不靠口头保证。

## 2. 设计原则（在 P41–P42 基础上新增 P43–P46）

**P43 微调再认证律（Re-certify-on-Update）**
任何模型更新 `θ→θ'` 都必须重签 FTAC；未签、失败或过期，则 θ' 视为**未认证**，回退旧 θ（或直接最保守模式）。证书必须携带 `(model_hash, calib_hash)`，任一不匹配即失效。同一模型下叠加本层只会收缩执行域。**推论**：证书的生命周期与模型版本强绑定，不再存在"训练一次、永久信任"的暗默认。

**P44 安全关键无退化律（No-Regression on Safety-Critical Slice）**
`FTAC(θ→θ')=1` 当且仅当在 `S_crit` 上同时成立：覆盖率 `≥1-α-ε_tol`；每类召回 `κ_c(θ') ≥ max(κ_c(θ), κ_req)`；输出稳定 `||f_{θ'}(x)-f_θ(x)|| ≤ ε_stable`；逐状态 `verdict_{θ'}(x) ⊑ verdict_θ(x)`。四项皆满足才"不更乐观"。故 `Exec_v23(θ')|_{S_crit} ⊆ Exec_v22(θ)|_{S_crit}`——微调只能在安全切片上收缩，不能偷偷扩张。

**P45 竞品只证伪律（Competitors Only Falsify）**
聚合 `Obs = Obs_self ∪ ⋃_c Obs_c`、`Free = Free_self ∩ ⋂_c Free_c`。竞品无权授予自由空间，只能撤销；`falsifies(c, claim, S)` 一旦成立即撤销该 claim 并沿依赖图传播。故 `Fil_cfs` 只减不增，`Exec_v23 ⊆ Exec_v22(θ')`。**竞品是"只会投反对票的评审"**——这是它能被无条件纳入安全侧的原因。

**P46 保守度预算律（Conservatism Budget Law）**
`ρ = Π_i ρ_i`（每 `ρ_i ≥ 1`），部署门槛 `ρ ≤ ρ_max`。超预算只触发**模块级保守度重分配**（把余量从过保守模块挪给紧模块），**从不豁免任何安全约束**。故活性调节与安全与门正交：调 ρ 不改变 `HPC-EC` 的通过与拒绝逻辑。

## 3. 与基线的接口（如何退化）

- FTAC 缺失/失败/过期 ⇒ θ' 未认证 ⇒ 用旧 θ 或最保守模式 ⇒ 比 v22 更保守 ⇒ 子集；
- CRA 越界（`||ΔW||>ρ`）⇒ 拒绝本次微调，保留旧 θ ⇒ 子集；
- 校准集与模型版本不匹配 ⇒ 相关证书 stale ⇒ 未赎回自由空间重新封闭 ⇒ 子集；
- CFS 火力全开或大量误报 ⇒ 障碍只增、自由空间只减 ⇒ 执行域只缩（活性下降由 SLCR 记账，不危及安全）；
- SLCR 超 `ρ_max` ⇒ 重分配保守度预算、不越过安全与门、不停机 ⇒ 执行域仍 ⊆；
- CFS 仅单源（无法判独立性）⇒ 该证据标为"非独立、仅保守计入" ⇒ 安全方向不变；
- 全失效 ⇒ 完全回退 v22 ⇒ `Exec_v23 ⊆ Exec_v22 ⊆ Exec_v21 ⊆ … ⊆ Exec_v18`（引理 170）。
- **安全继承的方向性**：模型更新靠"再认证"守（只会否掉更乐观的更新），外部压力靠"只证伪"守（只会撤销许可），活性靠"预算"守（只在模块间挪余量）。三者失效都向保守方向坍缩，没有一个失效路径能让执行域变大。

## 4. 预期贡献

16. **微调验收证书（FTAC）**：首次把"模型更新"纳入安全证书生命周期，用安全关键切片上的四项检验替代"平均精度"这一与安全无关的指标，使 v21 的 κ_c 经验假设在每次微调时被重新证明；
17. **可证残差适配（CRA）**：给出"冻结安全头 + 有界低秩残差 + Lipschitz 传播"的微调架构约束，把微调对证书输出的影响关进一个显式可算的球；
18. **竞品证伪集（CFS）**：把竞品分析重构为"持续红队/只投反对票的评审"，障碍保守并集、自由空间取交，首次让外部对手成为安全侧的可无条件纳入项；
19. **安全-活性竞争比（SLCR）**：把"保守是否过度"形式化为相对离线全知最优的竞争比，并按模块因子分解做保守度预算分配，正面给出 v22 活性坍缩风险的度量与缓解路径；
20. **双向"三明治"**：微调从内部移动边界、CFS 与 SLCR 从外部上下夹逼，安全性由"太乐观被证伪"守、活性由"太保守被记分"守；
21. **HPC-EC 统一门**：`HPC-E ∧ FTAC ∧ Unfalsified`，同模型严格子集、跨模型经 S_crit 再认证，`Exec_v23 ⊆ Exec_v22` 闭环。

## 5. 本轮最大风险

**一句话**：FTAC 全部效力押在"安全关键切片 S_crit 选对了"、CFS 全部效力押在"竞品与我们不是同一个盲区的产物"——若 S_crit 漏掉了真正的危险角落，且竞品集与自身感知又共享同源可见光/同源训练数据（评委与被考者是同一盲区的产物），则一次对儿童/轮椅/强逆光系统性漏检的微调会**"合格地"通过验收并被合规地部署**，竞品对拍沦为循环认证——"自己人给自己人盖章的缺席幻觉"。

## 1. 关键算法骨架（在 IP-431–435 骨架上扩展）

```python
# IP-436 微调验收证书
@dataclass
class FTAC:
    theta_hash: str
    calib_hash: str
    s_crit_hash: str
    kappa_c: dict          # θ' 上逐类召回下界
    coverage: float        # 目标域独立校准集上的实测覆盖
    eps_stable: float      # 实测输出变化上界
    verdict_le_base: bool  # 逐状态 verdict_{θ'} ⊑ verdict_θ

class FineTuneAcceptanceCertificate:
    def __init__(self, base_theta, s_crit, kappa_req, alpha,
                 eps_tol, eps_stable, delta_conf=0.05):
        self.base_theta, self.s_crit = base_theta, s_crit
        self.kappa_req, self.kappa_base = kappa_req, recall_lower(base_theta, s_crit)
        self.alpha, self.eps_tol = alpha, eps_tol
        self.eps_stable, self.delta_conf = eps_stable, delta_conf

    def verify(self, theta_prime, d_cal_prime, cert_fn):
        # (1) 覆盖率保持：用 θ' 在目标域独立校准集上重算 conformal 覆盖
        cov = empirical_coverage(cert_fn, theta_prime, d_cal_prime, self.alpha)
        cov_ok = cov >= 1 - self.alpha - self.eps_tol

        # (2) 召回下界不回退（Bonferroni 控 FWER）
        kappa = per_class_recall_lower(
            theta_prime, self.s_crit,
            delta=self.delta_conf / max(n_classes(self.s_crit), 1))
        rec_ok = all(kappa[c] >= max(self.kappa_req[c], self.kappa_base[c])
                     for c in kappa)

        # (3) 输出稳定界（由 IP-437 给出可证上界 + 实测双重校验）
        stable = output_shift_bound(theta_prime, self.base_theta, self.s_crit)
        stable_ok = stable <= self.eps_stable

        # (4) 逐状态不更乐观：UNSAFE ⊑ UNKNOWN ⊑ SAFE
        perm_ok = all(is_at_most_permissive(verdict(theta_prime, x),
                                            verdict(self.base_theta, x))
                      for x in self.s_crit)

        ok = cov_ok and rec_ok and stable_ok and perm_ok
        if not ok:
            return None            # 未认证 → 回退旧 θ 或最保守模式
        return FTAC(hash_of(theta_prime), hash_of(d_cal_prime),
                    hash_of(self.s_crit), kappa, cov, stable, perm_ok)

    def __init__(self, frozen_head, lip_head, rho_budget):
        self.head = freeze(frozen_head)   # 证书读取通路冻结（固定 ⇒ 可分析）
        self.L = lip_head                 # 安全头 Lipschitz 常数 L_f

class CompetitorFalsificationSet:
    def __init__(self, competitors):
        self.C = competitors

    def aggregate(self, obs_self, free_self):
        obs = set(obs_self)
        free = set(free_self)
        for c in self.C:
            obs |= c.obstacles()        # 只增障碍：保守并集
            free &= c.free_space()      # 只减自由空间：取交

        # 任何竞品在 claim 宣称的"空区"内检出人 → 证伪 AbsCert/CC
        return any(c.detects_person_in(region) for c in self.C)

        return (c.backend_id, c.data_source, c.derived_from)
```

## 2. 关键命题（供后续轮次继续编号）

**引理 167（逐状态单调 ⇒ 执行域收缩）**
若 `∀x∈S_crit: verdict_{θ'}(x) ⊑ verdict_θ(x)`，则 `{x∈S_crit : verdict_{θ'}(x)=SAFE} ⊆ {x∈S_crit : verdict_θ(x)=SAFE}`。配合 FTAC 的覆盖/召回/稳定三项，得 `Exec_v23(θ')|_{S_crit} ⊆ Exec_v22(θ)|_{S_crit}`。

**引理 168（竞品只证伪 ⇒ 安全）**
因 `Obs = Obs_self ∪ ⋃Obs_c ⊇ Obs_self` 且 `Free = Free_self ∩ ⋂Free_c ⊆ Free_self`，对任意计划 π 有 `Safe_agg(π) ⇒ Safe_self(π)`。CFS 只可能把"我们以为安全"改判为"不安全/未知"，绝不反向，故 `Fil_cfs` 单调收缩。

**命题 169（竞争比因子分解上界）**
在任务代价可乘分解、各模块约束近似独立的条件下 `ρ = Π_i ρ_i`；即使独立性不严格成立，`Π_i ρ_i` 仍是 ρ 的一个**可计算上界**（保守记账），足以把活性损失归因到具体模块并驱动保守度预算重分配。

**定理 170（v23 主继承）**
固定 θ 时 `Exec_v23(θ) = Exec_v22(θ) ∩ Fil_ft ∩ Fil_cfs ⊆ Exec_v22(θ)`；跨模型 `θ→θ'` 时，若 `FTAC(θ→θ')=1`，则 `S_crit` 上 `Exec_v23(θ') ⊆ Exec_v22(θ)`。SLCR 只影响部署准入与保守度参数、不进入安全与门。故 `Exec_v23 ⊆ Exec_v22 ⊆ … ⊆ Exec_v18` 在"同模型"与"跨模型再认证"两种意义下都闭合。

## 3. 实验设计（可执行草案）

**目的**：验证 FTAC 能在"平均精度提升但安全切片退化"的微调上正确拒绝；CFS 能提前暴露 AbsCert 漏检；SLCR 能诊断并缓解 v22 的活性坍缩。

**数据 / 切片**：以人体检测为重点，`S_crit` 显式覆盖 {儿童, 轮椅, 蹲姿, 逆光, 部分遮挡, 湿滑地面反光}。`D_cal'` 与测试集按**场景**（而非随机帧）划分，避免泄漏。

**竞品集 C**：{异构 LiDAR 检测器, 事件相机检测器, 独立训练的同架构检测器(不同种子/数据), 对抗策略, 人类红队标注}。记录 `backend_id / data_source / derived_from` 以判独立性。

**指标**：① 不安全放行率（含人区误签 AbsCert 的比例）；② 逐类召回下界 `κ_c` 及置信区间；③ FTAC 对 good/bad 两类微调的拒绝率；④ 竞争比 ρ 及分模块 `ρ_i`；⑤ 活性（任务完成时间 / 成功率）。

**消融**：去掉 FTAC → bad 微调被放行；去掉 CRA 冻结 → `ε_stable` 无法界定；去掉 CFS → 缺席幻觉上升；去掉 SLCR → 活性坍缩未被察觉。

## 4. 与 v22 模块的接线要点

- **FTAC ↔ DCSC**：DCSC 的 `α_dl` 覆盖在 `θ'` 上以 `D_cal'` 重算；模型哈希不符的旧证书一律 stale；
- **FTAC ↔ CAC/AbsCert**：`κ_c(θ') ≥ max(κ_c(θ), κ_req)` 直接给 AbsCert 的前提续命，杜绝"微调悄悄压低人体召回"；
- **CRA ↔ ACSC/能量模型**：安全头冻结与残差界同样适用于臂端与 `P=f_θ`，`ε_stable` 并入 `E_margin` 的保守记账；
- **CFS ↔ CFC++/GIC**：竞品证据按 `backend_id` 判独立，避免"多别名伪装多模态"；手势在场证据作为 CFS 的一条独立召回通道；
- **SLCR ↔ HDL/PGEV**：`ρ_i` 归因到 AbsCert/DCL/EVC/CFS，超预算只重分配保守余量，保持 `Fil_strategic ⊇ Fil_tactical ⊇ Fil_operational` 不变。
