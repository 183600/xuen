# 第 3 轮迭代（灵感循环 v3：「状态估计」×「开源软件」）—— 把“进度验证”重写为“计分状态的间歇滤波器”，用开源式契约钉死假设

> 本轮的首要动作是**换范式 + 修事实**，不是继续堆模块。v2 的旗舰把验证器做成阈值分类器（done/ongoing/fail/regressed），并假设“运行时改 `action_chunk_size` 来换重观测频率”。本轮直接读官方提交仓库的**可执行规格** `example/example_env.py`：action 形状被硬校验为 `(action_chunk_size, …)`，返回短块会 `ACTION REJECTED`。因此 `T_a` 是握手期常量；两次观测之间隔着整块开环执行；人为撤回只能在下一个块边界被看到。这把问题从“分类”改写成“**固定采样周期、部分可观测、带稀疏反向跳变的状态估计**”。同时，观测目录里**没有基座位姿、IMU、力/触觉**，只有 4 路 RGB + 双臂关节/末端位姿/夹爪 + `lower_body[15]`——所以“每一步都能验证”是错觉，必须做**可观测性审计**。

> “开源软件”给的不是又一套代码，而是研究纪律：**官方仓库是上游契约，`example_env` 是可执行规格，`info.json` 是需要 vendor + 锁 hash 的外部依赖，每个假设都要有回归测试。** 本轮命题：**用开源执行契约锁定接口事实，用状态估计处理接口之下的不确定性。**

**三条硬修正**：
1. **UIP-13 的“运行时自适应 k”不成立**：只能离线选一个全局 `T_a`（或验证是否允许按端口给不同 metadata）；返回短块会被拒。
2. **验证不是免费的**：4 路 RGB 有遮挡、无触觉，相当一部分计分谓词只能“间接推断”或“不可观测”；必须把观测预算当资源分配。
3. **基座位姿是潜变量**：末端位姿是 base frame，且无基座位姿观测；“挪底座”类干扰（T11/T25）必须通过场景相对运动估计，而不是假设已知。

## 1. 两个灵感词的解读

### 1.1 状态估计：从“跟踪一辆车”到“跟踪裁判的计分板”
**直觉**：卡尔曼滤波用带噪声的 GPS 跟踪车的位置；这里用带噪声的 4 路图像 + 本体感觉跟踪“裁判此刻会给哪几步分”。车会被别的车顶回去；任务进度会被人为“反向撤回”。滤波器的后验不确定性告诉你“该不该再看一眼/重做”，而不是拍脑袋设 0.6 阈值。
**严谨定义**：把任务写成 POMDP。隐藏计分状态 `z_t ∈ {0,1}^K`（K≤5，权重 w_k 合计 100），可行集 F 编码“有序/物理一致”约束；机器人本体状态由观测直接给出，真正隐藏的是物体/关节/计分状态。观测只在块边界到达，周期固定为 `T_a`；人为干扰是稀疏跳变算子 `R_m`（把已完成位翻回 0）。目标不是“分类 regressed”，而是维护信念 `b_t(z)` 并做**期望效用最优**的重做决策。关键红利：`K≤5 ⇒ |F|≤2^5=32`，**可以精确前向滤波，不需要粒子**，延迟可忽略。

### 1.2 开源软件：把“规范”变成“可执行契约”
**直觉**：开源项目能做大，不是因为代码多，而是因为接口稳定、依赖可锁、测试可回归、任何人能复现。比赛里最稀缺的不是代码，是**有效迭代次数**；开源纪律就是把每次迭代的“假设”变成可自动检验的契约。
**严谨定义**：把官方 `info.json` 当作上游 API（vendor 一份 + 锁 hash + 版本化），把 `example_env.py` 当作**可执行规格**（CI 里直接跑它做接口一致性测试），把每个任务的计分点/谓词/干扰写成声明式 `task.yaml`，再由编译器生成估计器配置、Gazebo 判分、技能图和测试。任何上游变更触发“重新生成 + diff 审查”，而不是静默漂移。这正是本轮发现“短块不合法”的机制——**读源码而不是读散文**。

## 2. 对 v2 清单的诊断

- **升级为旗舰**：UIP-01′ → **UIP-16 SSBF**（阈值分类器 → 计分状态信念滤波）；UIP-09′ → 同一滤波器的 `R_m` 跳变分支 + CUSUM 检测；UIP-15′ → 用**贝叶斯最优成本阈值**替代 0.6。
- **纠错重写**：UIP-13 ACS → **UIP-17 DCC**（固定 `T_a` 的离线可检测性优化，而非运行时变 k）。
- **升级观测工程**：UIP-08′ → 观测预算分配（状态键密集堆叠、图像键稀疏堆叠、每端口隔离）。
- **保留并重新定位**：UIP-11 GSO → 作为 SSBF 的**带真值测试夹具**；UIP-12 DRF → 生成“撤回-恢复”真值轨迹；UIP-14 MSGR → 提供转移先验（本块“打算完成哪些步”）；UIP-05 LCAG → 语言条件化，保留。
- **新增**：UIP-18 OAP（可观测性审计 + 主动观测）、UIP-19 TCC（任务契约编译）、UIP-20 RTH（回放回归测试台）、UIP-21 OSS-BB（开源骨干 + 许可证审计）。

## 3. 瓶颈假设（v3）

- **H1（最高风险）**：计分语义未定。若步骤分按“曾经达成”入账，则“撤回→重做”对**步骤分**的直接收益消失，只剩成功率收益；若成功率也按“曾经达成”，整套恢复闭环价值归零。
- **H2（结构性）**：观测周期固定为 `T_a` ⇒ 撤回检测延迟有下界；`T_a` 是编译期超参，不是运行期旋钮。反应性只能靠“更小的全局 T_a / 端口异构 / 减少盲目前进”换。
- **H3（被低估）**：可观测量不足。无基座位姿、无力/触觉、相机遮挡 ⇒ 一部分计分步不可直接验证；需要“构造式可验证”（让完成动作本身留下可见证据）和主动观测。
- **H4（工程）**：官方校验器是开源可执行规格；散文与注释可能过时。接口事实必须以 `example_env` 为准，并纳入 CI。
- **H5（策略）**：开源骨干能极大提高迭代吞吐，但许可证与“单模型”合规是约束；开源自己的任务契约/干扰数据会削弱相对优势，应采用“open-core”。

## 4. v3 清单（详见产物区）
旗舰从“验证-重做”升级为“**信念估计 → 可检测性调度 → 可观测性感知 → 贝叶斯重做**”的闭环；UIP-16/17/18 是方法核心，UIP-19/20 是把方法钉在可复现工程上的两条腿，UIP-11/12 退居“真值夹具”。本轮不再新增“更多技能模块”，而是把**不确定性**作为一等公民。

## 5. 本轮押注
**押注 UIP-16 SSBF × UIP-17 DCC × UIP-18 OAP**：先证明“固定采样周期下的计分状态可被可靠滤波”，再证明“按可检测性选 T_a 比拍脑袋选块长更优”，最后用可观测性审计决定“哪些步值得重做、哪些步只能一次做对”。UIP-19/20 保证这套东西在远程、不可调试的评测里不静默失效。

**一句话最大风险**：整套方案押在一个尚未核实的计分语义上——若步骤分（乃至成功率）按“曾经达成”而非“结束时状态”结算，撤回检测-重做的收益会大幅缩水甚至归零；必须先证实/证伪它，再投入工程。

### 0.2 修正 1：`T_a` 是编译期常量，不是运行期旋钮

```python
# example/example_env.py, step()
if action[action_key].shape != (self.action_chunk_size, *self.action_spec[action_key]):
    raise ActionError(
        f"action[{action_key}].shape {action[action_key].shape} "
        f"!= expected {(self.action_chunk_size, *self.action_spec[action_key])}"
    )
```

**结论**：v2 的“接触密集步用小 k、运输步用大 k”在接口层无法实现。只能：
1. 选一个全局 `T_a`（默认、最稳）；
2. 若评测确实允许**按端口**返回不同 metadata，则做端口异构（需向主办方确认，且有“钻空子”观感风险）；
3. 用“动作内容”控制**盲目前进量**（例如块内后段返回保持动作），但**不能降低观测周期/检测延迟**，只降低“盲执行造成的不可逆进度”。

必须区分两个量：
- **观测周期** `T_a`：两次看到世界的间隔（由接口固定）；
- **承诺视界** `m ≤ T_a`：一个块里真正推进任务的前 m 步，其余为安全保持。
`m` 可以缩短“盲推进”，但检测人为撤回仍然只能在 `T_a` 边界发生。

### 0.3 修正 2：部分可观测，必须做可观测性审计

无基座位姿、无 IMU、无力/触觉、4 路相机存在自遮挡/夹爪遮挡。因此计分谓词分三类：
- **D（直接）**：相机可直接判，如“碗叠在碗上”“书在架上”；
- **I（间接）**：靠本体（夹爪开合、末端位姿）+ 几何/时序推断，如“夹住了”“插入深度”；
- **U（不可观测）**：当前传感器无法可靠判，如“拉链另一侧完全闭合”“连接器内部卡扣”“针管内部液面”。

**U 类步骤不能靠“反复重做验证”**，只能“一次做对 + 构造式可验证 + 少量探针”。

### 0.4 修正 3：基座位姿是潜变量

`ee_pose_gripper_base` 是**base frame** 下的位姿；`lower_body[15]` 是下肢本体感觉，不等价于基座位姿。若人移动底座（T11/T25），末端位姿不会直接暴露该变化。必须把基座位姿 `x_b` 加入隐藏状态，用高位相机的**静态场景流/已知地标**估计，否则“底座被挪”会被误判成“物体被挪”。

## 1. 旗舰：UIP-16 SSBF（Scoring-State Belief Filter）

### 1.1 状态、权重与可行集

任务有 K 个计分步，权重 `w ∈ R^K`，`Σ_k w_k = 100`（K≤5）。隐藏计分状态：

```
z_t ∈ {0,1}^K,   z_t[k] = 1  表示第 k 个计分步“此刻仍满足”
F ⊆ {0,1}^K    物理/顺序可行集
```

- 严格有序任务：`F = {0, e_1, e_1+e_2, …, 1}`，只有 `K+1 ≤ 6` 个状态；
- 允许部分乱序的任务：`|F| ≤ 2^K ≤ 32`。

因此**精确前向滤波是可行的**：每块 O(|F|²) ≤ 1024 次标量运算，完全在延迟预算内，无需粒子滤波。

### 1.2 转移模型：一个块 = 一个离散时间步

设当前块打算完成 `Δ(a_t) ⊆ {1..K}`（来自 UIP-14 技能图的当前子目标）。单步完成概率 `p_commit[k]`。机器人的“推进”：

```
z⁻ = z_t ∨ Δ_eff,   Δ_eff[k] ~ Bernoulli(p_commit[k])
```

人为干扰是稀疏跳变算子 `R_m`（把若干已完成位翻回 0，再投影回 F）：

```
R_m(z)[k] = 0,  k ∈ revert(m)
R_m(z) ← Proj_F(R_m(z))        # 例如有序任务中撤销 s2 ⇒ s3 也失效
```

一个块内至少发生一次干扰的概率 `η = 1 − exp(−T_a · Σ_m λ_m)`；干扰类型按 `π_m = λ_m / Σ_m λ_m`。转移：

```
T(z' | z, a) = (1−ε) [ (1−η)·1{z' = z⁻} + η·Σ_m π_m·1{z' = R_m(z⁻)} ]
             + ε·Uniform(F)
```

`ε` 是模型失配/未建模动作的兜底。**反应性风险率**：`λ_m` 在“刚完成 s_k 后”的短窗口内更高（对应“合上后再打开”“拉上后再拉开”）：

```
λ_m(t) = λ_m^0 · (1 + κ·1{某个 revert(m) 的目标步在最近 τ 步内刚完成})
```

这让滤波器能“预期”干扰，而不是事后惊讶。

### 1.3 观测模型：把 4 路 RGB + 本体变成逐位似然比

对每个计分位 k，定义校准后的似然比：

```
ℓ_k(o) = P(o | z_k=1) / P(o | z_k=0)
```

- **D 类**：几何谓词来自高位/腕部 RGB（检测、配准、堆叠/接触几何）；
- **I 类**：本体签名（夹爪开合、末端位姿相对已知工位、关节轨迹的单调性）+ 视觉弱证据；
- **U 类**：`ℓ_k ≡ 1`（不提供信息，后验只随转移模型漂移）。

观测似然（朴素贝叶斯近似，独立同分布假设需用回放数据检验）：

```
L(o | z) ∝ Π_k ℓ_k(o)^{z_k}
```

校准：在回放/仿真真值上用温度缩放或 isotonic 回归校准 `ℓ_k`，CI 门禁 ECE ≤ 0.05。**未校准的似然比会让贝叶斯决策比 0.6 阈值更糟**。

### 1.4 信念递推（精确、廉价）

```
预测：  b⁻(z') = Σ_z T(z' | z, a_t) · b_t(z)
更新：  b_{t+1}(z') ∝ L(o_{t+1} | z') · b⁻(z')
边缘：  p_k = P(z_k=1) = Σ_{z: z_k=1} b(z)
```

初始化：`reset()` 后 `b_0 = δ_{0}`（假设重置后无步骤完成）；若首帧显示已有状态，用首帧观测更新一次。

### 1.5 贝叶斯最优重做：用成本阈值替代 0.6

设重做第 k 步的成本 `c_k`（时间 + 破坏其他步骤的风险 + 可信度抖动），重做成功率 `q_k`。不重做的期望损失是 `w_k · (1−p_k)`（若计分按结束时状态）。则：

```
重做 iff  w_k · (1 − p_k) · q_k > c_k
等价阈值： 1 − p_k > τ_k,   τ_k = c_k / (w_k · q_k)
```

- 权重 40 的末步 ⇒ `τ` 更小（更愿意重做）；权重 20 的前置步 ⇒ `τ` 更大（更愿意保）。
- 有序任务中“重做 s_k”通常意味着重做后缀 `s_k..s_K`；此时用后缀总权重 `Σ_{j≥k} w_j` 与后缀总成本 `Σ_{j≥k} c_j`，不要单步算。
- **滞回**：连续两次越阈值才重做，或用 1.7 的 CUSUM，避免“重做→误判→再重做”的振荡。

### 1.6 对计分语义的鲁棒化（对冲 H1）

同时维护两个量：
- `p_k`：**此刻**满足的概率（会随撤回下降）；
- `m_k`：**曾经**满足过的概率（单调不减，`m_k' = m_k + (1−m_k)·P(z_k=1)`）。

两种计分语义对应两个目标：
```
结束时状态结算：  J_end  = Σ_k w_k · p_k
曾经达成即入账：  J_bank = Σ_k w_k · m_k
```
语义未知时优化 `J_γ = γ·J_end + (1−γ)·J_bank`，或做 min-max 稳健决策。若手册确认按“曾经达成”，则 `γ=0`：步骤分不再需要重做，重做只服务于**最终成功率**；若确认按“结束时状态”，则 `γ=1`，全力恢复。**这个开关必须有，不能把假设写死。**

### 1.7 撤回检测：CUSUM 而不是单帧阈值

```
s_k(t) = log( p_k(t) / (1 − p_k(t)) )
e_k(t) = s_k⁻(t) − s_k⁺(t)          # 观测让“仍完成”的 log-odds 掉了多少
g_k(t) = max(0, g_k(t−1) + e_k(t) − ν)
告警：g_k(t) > h
```

- `ν` 是容忍漂移，`h` 由目标 ARL（例如每 100 episode ≤ 1 次误报）与检测延迟共同标定；
- CUSUM 不需要已知干扰发生时刻，适合“未知何时被撤回”的评测；
- 与 SSBF 的关系：SSBF 给后验，CUSUM 给**低延迟告警 + 可解释的诊断**；两者共享同一组 `ℓ_k`。

### 1.8 伪代码

```python
class SSBF:
    """Exact belief filter over <= 2^5 scoring states + CUSUM alarms."""
    def __init__(self, K, weights, feasible, hazard, p_commit,
                 likelihoods, redo_cost, redo_success, gamma=1.0,
                 cusum_nu=0.2, cusum_h=3.0):
        self.K, self.w = K, weights
        self.F = list(feasible)                 # list[tuple[int,...]]
        self.index = {z: i for i, z in enumerate(self.F)}
        self.T0 = self._build_transition(hazard, p_commit)
        self.lik = likelihoods                 # k -> callable(o)->log ell_k
        self.c, self.q, self.gamma = redo_cost, redo_success, gamma
        self.nu, self.h = cusum_nu, cusum_h
        self.b = None
        self.g = [0.0] * K
        self.m = [0.0] * K                     # P(ever achieved)

    def reset(self):
        self.b = zeros(len(self.F)); self.b[self.index[(0,)*self.K]] = 1.0
        self.g = [0.0] * self.K; self.m = [0.0] * self.K

    def predict(self, intended_steps):
        T = self._transition(intended_steps)   # 枚举 F×F，含 R_m 与 Proj_F
        self.b = T.T @ self.b

    def update(self, obs):
        loglik = []
        for z in self.F:
            ll = sum(self.lik[k](obs) for k in range(self.K) if z[k])
            loglik.append(ll)
        loglik = np.asarray(loglik); loglik -= loglik.max()
        self.b = self.b * np.exp(loglik)
        self.b /= self.b.sum()
        p = self.marginals()
        for k in range(self.K):
            s = logit(p[k])
            e = self._pred_logit[k] - s
            self.g[k] = max(0.0, self.g[k] + e - self.nu)
            self.m[k] = self.m[k] + (1 - self.m[k]) * p[k]
        self._pred_logit = [logit(x) for x in p]

    def marginals(self):
        p = np.zeros(self.K)
        for z, bz in zip(self.F, self.b):
            p += bz * np.asarray(z)
        return p

    def redo_decision(self, suffix_weight, suffix_cost):
        p = self.marginals()
        J_end = float(self.w @ p)
        J_bank = float(self.w @ np.asarray(self.m))
        J = self.gamma * J_end + (1 - self.gamma) * J_bank
        # 找到最低的未完成“前沿”步，按后缀评估
        plan = []
        for k in range(self.K):
            gain = suffix_weight[k] * (1 - p[k]) * self.q[k]
            if gain > suffix_cost[k] or self.g[k] > self.h:
                plan.append(k)
        return plan, J, p
```

> 说明：真实实现里 `_build_transition` 只对 `|F|²` 的稀疏非零项求和；`T_a` 通过 `η=1−exp(−T_aΣλ)` 进入，不需要每步重建。`logit` 需裁剪防止 0/1 溢出。

### 1.9 与 v2 的差异

| v2 | v3 | 改动理由 |
|---|---|---|
| UIP-01′ 阈值分类 done/ongoing/fail/regressed | 信念 `b(z)` + 边缘 `p_k` | 保留不确定性，不把“看不清”当“没发生” |
| UIP-09′ 单独“检测撤回”模块 | `R_m` 跳变项 + CUSUM | 同一模型里做预测/检测，不重复建模 |
| UIP-15′ 固定 `conf_thr=0.6` | 成本阈值 `c_k/(w_k q_k)` + 滞回 | 不同权重/成本的步应有不同阈值 |
| 只优化“当前进度” | 同时维护 `p_k` 与 `m_k`，`γ` 对冲计分语义 | H1 未定时不把鸡蛋放一个篮子 |

## 2. UIP-17 DCC（Detectability-Constrained Chunking）

### 2.1 检测延迟的结构性下界

若撤回发生在控制步 `τ`，下一次观测在 `⌈τ/T_a⌉·T_a`，因此

```
d(τ) = ⌈τ/T_a⌉·T_a − τ ∈ [0, T_a]
E[d] ≈ T_a/2（均匀假设）；反应性干扰常发生在“刚完成”后 ⇒ 更接近 T_a
```

**结论**：`T_a` 直接决定“撤回后要带伤走多久”。这不是工程细节，是状态估计的采样定理式约束。

### 2.2 设计目标（示意，参数由 Gazebo 扫参得到）

```
J(T_a) = Σ_k w_k · λ_k · E[ min(d_k(T_a) + R_k, H − τ_k) ] / H
         + β · C(T_a)

C(T_a) = (H / T_a)·c_call + γ·Var[latency](T_a) + δ·SmoothnessPenalty(T_a)
```

- 第一项：撤回造成的“带伤时间”期望损失（`R_k` 是修复耗时，`H` 是 episode 视界）；
- `C(T_a)`：调用次数、延迟抖动、动作规律性/可信度成本；
- 小 `T_a` 降低第一项、抬高第二项；最优点由**扫参**决定，不靠拍脑袋。

### 2.3 对 v2 UIP-13 的纠错

- **删除**“运行时按阶段选 k”：接口不允许。
- **保留**“块长/反应性/延迟是策略级决策”，但改为**离线全局 `T_a` 选择**。
- **可选**：若确认允许按端口不同 metadata，则端口异构（小 `T_a` 端口处理接触密集任务，大 `T_a` 端口处理运输任务）；否则不要赌。
- **不要**用“返回短块”规避；会被 `ACTION REJECTED`（已由源码确认）。
- **可用但需计成本**：块内后段填充“保持”动作以缩短**承诺视界** `m`；它不降低检测延迟，只降低“盲执行造成的不可逆进度”，且可能被统计规律性检查注意到。

### 2.4 实践建议

1. 在 Gazebo + DRF（v2 UIP-12）里扫 `T_a ∈ {1,2,4,8,16}`；
2. 对每个任务族记录：检测延迟、步骤分、成功率、p95 延迟、动作抖动；
3. 选一个全局 `T_a`（单端口最稳），或给出“端口异构”的收益上界；
4. 若收益不足以抵消可信度/合规风险，选保守的较大 `T_a`，把资源投到 UIP-18 的可观测性上。

## 3. UIP-18 OAP（Observability-Aware Perception & Planning）

### 3.1 可观测性审计

对每个计分步 k，用回放/仿真估计：

```
O_k = I(z_k ; o_t | h_t) / H(z_k)     # 归一化互信息
```

工程上用校准后的谓词估计器 AUC 近似：`AUC ≥ 0.9` → D；`0.7–0.9` → I；`< 0.7` → U。

| 任务/步 | 谓词 | 可用证据 | 分级 | 策略 |
|---|---|---|---|---|
| T27 s2/s3 | 碗叠碗 | 高位相机几何 | D | 视觉似然 + 低成本核对 |
| T26 s3 | RJ45 插到位 | 末端位姿 + 端口位姿 + 腕部图 | I | 本体几何 + 小幅回拉探针（谨慎） |
| T19 s2 | 拉链闭合 | 腕部图局部可见，另一侧遮挡 | I/U | 构造式可验证：拉过止点，让拉头位置可见 |
| T16 s2 | 毛巾折叠 | 高位图 + 折边几何 | I | 多视角 + 折边连续性 |
| T14 s2 | 瓶盖拧回 | 腕部图 + 末端 yaw | I | 旋转签名 + 视觉 |
| T25 s3 | 底座被挪 | 无基座位姿；高位场景流 | U | 把 `x_b` 加入滤波，用静态地标重定位 |
| T31 内部 | 文具袋内部拉链 | 袋内遮挡 | U | 不做反复验证；一次做对 + 外部可见收尾 |

**审计产出**：每任务一张 `observability.json`，驱动“哪些步值得重做、哪些步只能一次做对”。

### 3.2 策略矩阵

| 分级 | 估计器 | 重做策略 | 动作策略 |
|---|---|---|---|
| D | 视觉几何谓词 + 校准 | 正常贝叶斯重做 | 常规 |
| I | 本体 + 几何 + 时序融合 | 高阈值、需 CUSUM 确认 | 优先“可验证收尾姿态” |
| U | `ℓ=1`，仅靠转移先验 | **不重做**（省预算） | 一次做对 + 保护 + 构造式验证 |

### 3.3 主动观测：块末姿态是唯一免费的“传感器放置”

由于块内不能重观测，唯一能在不额外调用的情况下改善观测的旋钮是**块末的末端/腕部姿态**。对候选动作块 `a`，定义信息价值：

```
VoI(a) = E_{o'}[ max_{a'} U(a', b') ] − max_{a'} U(a', b) − cost(a)
```

在“预测任务进度相近”的候选块中，选 `VoI` 最大者（例如让腕部相机在收尾时扫过拉链/插口/液面）。若策略是生成式的，可对 top-k 采样重排序；若确定性，可追加一个**安全的“瞥一眼”收尾**，但必须计入时间与动作规律性成本。

### 3.4 构造式可验证（Verification-by-Construction）

优先选择“完成动作本身留下可见证据”的执行方式：
- 拉链：拉过止点，使拉头停在可见位置；
- 瓶盖：拧到标记朝上/朝外；
- 插头：插到法兰贴合，侧视可见缝隙消失；
- 叠碗：最上碗的碗沿在相机中形成预期轮廓。
在多个“都能成功”的方案中，选**末态最可观测**的那个。这把“验证”从事后检查变成动作设计的一部分。

### 3.5 基座位姿增广

隐藏状态加 `x_b ∈ SE(2)`（桌面任务可降维）。观测模型：
```
x_b 的观测 = 高位相机中静态地标/桌沿的位移（场景流）
ee 的 base-frame 位姿不能直接观测 x_b（会与“物体移动”混淆）
lower_body 只作弱先验
```
这一步直接决定 T11/T25 的“挪底座”干扰能否被正确归因。

### 4.3 UIP-20 RTH：Replay Test Harness

**真值来源**：

## 8. 风险与合规（本轮重点）

1. **H1 计分语义（阻塞级）**：若步骤分/成功率按“曾经达成”结算，重做收益大幅缩水。先做 E201；在设计上保留 `γ` 开关，别把假设写死。
2. **仿真过拟合**：GSO/DRF 只作“结构/顺序/恢复”裁判，不作像素级成败裁判；真机时段做锚点。
3. **可观测性误分类**：把 U 类误判成 D 类会导致“自信地重做/不重做”；审计要用 held-out 任务与多视角，保留 `ℓ=1` 的保守兜底。
4. **接口红线**：形状严格 `(T_a,…)`、dtype float32、token 两处校验、`joint`/`ee` 互斥；返回短块/未知键直接拒。
5. **可信度**：块内填充保持动作、频繁重做、延迟抖动都可能被统计规律性检查注意到；把“可信度成本”显式放进 `c_k` 与 `C(T_a)`。
6. **开源合规**：许可证/商用/再分发/“单模型”解释；必须有降级方案。
7. **远程不可调试**：飞行记录器 + 确定性重放是必需品，不是加分项。

## 10. 本轮押注 & 最大风险

**→ 押注：UIP-16 SSBF × UIP-17 DCC × UIP-18 OAP**——先用状态估计把“裁判此刻会给多少分”变成可计算的后验，再用可检测性约束选 `T_a`，最后用可观测性审计决定“哪些步值得重做、哪些步只能一次做对”；UIP-19/20 用开源式契约与回放门禁保证它在远程评测中不静默失效。

**一句话最大风险**：整套方案押在一个尚未核实的计分语义上——若步骤分（乃至成功率）按“曾经达成”而非“结束时状态”结算，撤回检测-重做的收益会大幅缩水甚至归零；必须先证实/证伪它，再投入工程。
