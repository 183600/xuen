# 第 8 轮 · AEG：把 180 秒当电池，把 chunk 当受控对象

> 检索/复核日期：2026-10-26（UTC）。赛事身份不变：宇树科技 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮先做了三件不讨喜但必要的事：**把榜单打假、把规则读细、把第 7 轮的算术重算**。结论是：第 7 轮「放置是成功闸门」仍然成立，但「放置占约 60% 步骤分，所以是大头」必须降级——官方排名是**总平均成功率优先，步骤分只在成功率相同时才起作用**；用户看到的「榜首不到 30%」也不是真实榜单，而是占位脚本生成的 29.7%。真正被低估的约束是：**每次 trial 180 秒硬超时、full eval 320 次、chunk 在 handshake 固定且中途不能重规划**。于是本轮把研究火力从「再训一个更大的 VLA」转到「冻结 VLA 外面的执行治理层」：**AEG（Adaptive Execution Governor）**。

## 0. 本轮先核实：六个事实与一次纠错

### 0.1 榜单仍是占位：29.7% 不是真实成绩

三重证据（[S3][S4][S5]，2026-10-26 复核）：

1. `leaderboard.html` 直连仍显示「即将发布 / Coming Soon」。
2. `leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，发布于 **2026-10-08**；8 个模型 × 32 任务 = 256 条 `task_metrics` 全部由脚本生成。
3. `runs.html` 是 `256 / 256` 条占位记录；`details.html` 的 32 个任务详情全部写「测试视频占位，后续可替换为真实视频文件」（实测 32 处）。

占位榜的 8 个模型（成功率 / 步骤分）：

| 排名 | 模型 / 用户 | 成功率 | 步骤分 |
|---|---|---|---|
| 1 | MolmoAct2 / DexHacker | 29.7% | 39.0 |
| 2 | WALL-OSS-0.5 / Generalist Robotics | 28.5% | 38.9 |
| 3 | DreamZero / World Model Lab | 27.9% | 37.9 |
| 4 | Spirit-v1.5 / VLAGO | 25.9% | 34.4 |
| 5 | DM0 / Embodied AI Institute | 23.5% | 31.7 |
| 6 | PI-0.5 / RoboReasoner | 22.8% | 30.6 |
| 7 | GigaBrain-0 / xembody | 22.6% | 29.5 |
| 8 | GR00T N1.5 / Humanoid Dynamics | 20.5% | 28.1 |

取证：corr(成功率, 步骤分)=**0.998**；corr(成功率, 时长)≈**0.003**；步骤分≈成功率+约 8。这是合成数据的典型指纹，不是评测结果。**因此本轮不再从「占位榜第一名」推断真实头部团队做法；8 个模型只能当作公开模型家族的代理样本。**

### 0.2 排名规则：成功率先行，步骤分只是 tie-break

中文手册原文（[S6]）：

> 实时榜单按32个任务的 **总平均成功率** 进行排序，成功率相同时按 **总平均步骤分** 排序，若仍相同，则提交日期较早的模型排序靠前。

英文手册同义（[S7]）：

> The real-time leaderboard is sorted by overall average success rate across all 32 tasks. In the event of a tie, the overall average step score is used as the differentiator. If still tied, earlier submission dates rank higher.

官网营销文案写「按平均成功率与步骤分综合排序」，但手册评分章节是**字典序**：先成功率，后步骤分，再提交时间。以手册为准。

这条规则的含义被第 7 轮高估了：

- **成功率 +1pp 的价值，原则上大于任何步骤分增益**，除非两个模型成功率完全相同。
- 320 次 trial 的成功率粒度是 1/320=**0.3125pp**；成功率相同（tie）并非不可能，但步骤分只在 tie 时才有意义。
- 第 7 轮的「终局步骤占 39.8%、放置类步骤约 59.7%」仍然有用——它说明**终局是成功闸门、放置是终局主动作**——但不能再说成「放置占 60% 权重」。**放置优先的理由从「步骤分大头」改为「成功闸门 + 失败集中点」。**

### 0.3 180 秒 + 320 次 trial：评测是一场有硬预算的战役

手册与任务页（[S2][S6][S7]）：

- 32 任务 × 每任务 10 次独立运行 = **320 次 trial**；5 类泛化（位置/干扰物/背景/未见物品/人为干扰）各 2 次。
- 单次真机最长 **180 秒**；超时记失败，并按执行情况计算步骤分。
- 排行榜是 32 个任务平均成功率的再平均。

三个直接后果：

1. **成功优先，时间不是 KPI。** 只要能在 180 秒内救回来，多花时间也值得；提前完成不直接加分（步骤分只在 tie 时用）。第 7 轮把「步骤分效率」当主目标的倾向要收。
2. **超时是悬崖。** HangCup 演示中位数约 5.9 秒（177 帧 @30fps），但长程任务（折毛巾、拉拉链、装笔盒、插网线）可能几十秒；一旦进入「抓取失败→重试→再失败」的循环，180 秒会被吃光。
3. **320 次 trial 的统计噪声不可忽视。** p≈0.3 时，单次 full eval 的 95% CI 约 ±5pp；任务内 10 次运行高度相关，必须按 task 做 cluster bootstrap，不能把 320 次当独立样本吹显著。

### 0.4 API v2：chunk 在 handshake 固定，中途不能重规划

`unibot_submission` README（[S8]，v2，仓库最近提交 2026-08-21）确认：

- `action_chunk_size` 在 handshake 时固定；`get_action` 在**整段 chunk 执行完之后**才再次调用，**没有 mid-chunk replan**。
- metadata 字段：`control_space`（joint / ee 互斥）、`obs_delta_indices`（键决定传哪些观测，值决定每键堆叠帧）、`image_resize`、`action_chunk_size`、`token`。
- 观测：4 路 RGB（head stereo L/R + wrist L/R，480×640）、双臂关节/EE 位姿（base 系）、夹爪、lower_body、`observation.language` 单字符串。
- N 端口并发、每端口独立状态；延迟、延迟稳定性、动作规律性会被记录，官方建议避免不规则交互。

这条约束直接堵死了 2026 年一批「自适应 horizon」论文的用法：AutoHorizon、AAC、GeoAAC 等（[S26][S27][S28]）可以在 chunk 边界改 horizon 或触发重规划，但 UniBot 的 chunk 长度是固定的。**能做的只有两件事：在 chunk 内部做轨迹整形（重定时、柔顺、安全收尾），在 chunk 边界做验证、记忆检索和预算决策。** 这正是 AEG 的边界。

### 0.6 G1 电池：字面不可控，但「电池管理」是正确隐喻

G1 公开规格：9000mAh、421.2Wh、46.8V、约 2 小时、BMS、快拆（[S14]）。参赛者不控制电池，字面「电池管理」不是评分杠杆。但这场评测本身像一块电池：

- **SOC**：单次 episode 剩余时间 R/180；
- **SOH**：机器人标定质量（跟踪误差基线、夹爪迟滞、相机外参漂移）；
- **SOP**：当前健康度和接触相位下允许的最大动作速度/柔顺度；
- **热降额**：远程 API 的延迟/抖动、执行器发热导致的增益漂移；
- **充放电**：成功 episode 把「成功放置位姿/恢复段/标定参数」充进战役记忆；失败 episode 放电并降低先验置信度。

**字面电池管理不可做；把 180 秒当 SOC、把标定当 SOH、把重试当高电流脉冲的 BMS，是可做的，而且与成功率先行的排名完全对齐。**

## 1. 三个灵感词，各自钉到本轮事实上

### 1.1 创新点挖掘：从「模型能力」转向「执行治理」

第 5–7 轮一直在模型侧找创新：更大的 VLA、世界模型、检索上下文、放置位姿迁移。它们都对，但边际收益越来越不确定，因为：

- 真实桌面榜上，通才模型大致 17–51%，专家微调 35–64%；**模型规模不是唯一瓶颈**。
- Spirit-v1.5 的失败集中在插网线、排序、折布、扫码——**接触丰富、长程、终局验证**，不是「看不懂语言」。
- 2026 年一批执行层论文给出的增益很大且便宜：APEX 插入任务 +4.8–25.8pp、RoboPace 64% vs 44%、CheckVLA 比周期重规划 +8.5pp、Retrieve-then-Steer 长程 +12.5pp、Time-Aware 效率 +48% 且成功率不降（[S20]–[S25]）。

所以本轮对「创新点」的定义改成三条硬标准：

1. 是否改变**官方排名**（成功率优先）？
2. 是否与「换更大模型」**正交**？
3. 是否能在 **API v2 + 180 秒 + 固定 chunk** 内落地？

AEG 三条都过。它不是新的 VLA 架构，而是把冻结 VLA 变成「成功优先的闭环系统」的治理层。

### 1.2 电池管理：SOC/SOH/SOP → episode 预算与重试决策

把 BMS 的状态估计搬到 episode：

- **SOC(t)=R/180**，R 为剩余秒数；
- **SOH** 由标定质量 c∈[0,1] 表示：跟踪误差基线、夹爪开合迟滞、相机外参漂移、TCP 偏差；
- **SOP(c, φ)** 是当前健康度与接触相位 φ 下允许的最大速度/最小柔顺度；
- **热降额** 用 RTT 与 jitter 估计，延迟越大，SOP 越低；
- **终局 reserve**：不管前面怎么救，必须给终局放置/插入/验证留 r_term 秒（默认 15s，长程任务 25s；用调试槽实测终局段耗时 +5s 标定，不用整段演示时长直接冒充）。

一个可算的决策规则（细节在产物区）：

```text
在 chunk 边界，给定剩余时间 R、当前子任务 i、成功信念 b：
  若 R < r_term + 终局最短耗时 → 放弃可选重试，直接尝试终局
  若 R ≥ r_term + 重试耗时 + 重试后终局耗时
     且 重试的边际成功增益 > 0 → 允许重试
  否则 → 继续当前子任务，或在安全姿态早停（早停只省平台时间，不省分数）
```

注意：**超时和早停都是失败，早停没有分数收益**；BMS 的价值不是「早停」，而是「把时间花在能提高成功率的重试上，并保证终局有钱花」。

### 1.3 自适应控制：chunk 内的跟踪补偿、重定时、柔顺、安全收尾

固定 chunk 意味着策略在 H 步内是开环的；机器人底层会跟踪目标，但模型看不到中段观测。AEG-AEC 做四件事：

1. **跟踪误差观测器**：用上一段 `q_cmd` 与当前 `q_obs` 估计执行器偏置 b、增益 g、摩擦 f（RLS/MRAC 式），下一段做逆补偿；这对应 Self-Adaptive VLA 的硬件偏移适应（[S22]）。
2. **重定时**：按相位（自由/接近/接触/收尾）对 chunk 轨迹做时间/空间重采样；自由段快、接触段慢、收尾更慢。因为 chunk 时长固定，**「慢」是通过每步走更小的空间增量实现的**，代价是覆盖同样距离需要更多 chunk；180 秒预算允许这种交换。
3. **柔顺轨迹整形**：没有力矩/阻抗接口，就用「低速+小步+横向搜索+跟踪误差触发回退」实现行为级柔顺；插入类任务用 1–3mm 螺旋/侧向抖动，堆叠类最后 2cm 降速，拉链类维持小幅张力。对应 Imp-ACT 的方向相关柔顺证据（[S31]），但明确是轨迹级而非力控级。
4. **安全收尾**：每个 chunk 的最后几步设计成「安全 via-point」（例如插入前退 5mm、堆叠后停住），这样即使下一段观测延迟，机器人也不会停在危险姿态；RTT/jitter 超阈值时整体降速并缩短空间步长。对应 CheckVLA 的 latency-aware hard prefixing 思路（[S23]）。

### 1.4 三个词为什么在第 8 轮汇合

- **创新点挖掘**告诉我们：不要再从「模型更大」里找；去规则结构里找被低估的约束。
- **电池管理**给出约束的语言：180 秒是 SOC，标定是 SOH，重试是脉冲，终局是 reserve。
- **自适应控制**给出执行的语言：chunk 是受控对象，跟踪误差是扰动，柔顺/重定时/安全收尾是控制律。

三者合成一句话：**用 BMS 的预算逻辑决定「要不要救」，用自适应控制的 chunk 整形决定「怎么救」，用战役记忆决定「从哪次成功里救」。**

## 2. 本轮主判断：AEG 三环

### 2.1 架构总览

```text
语言(160条复述之一) + 4路RGB + 本体状态
        │
        ▼
  冻结 VLA（单一 checkpoint，不改权重）
        │  action chunk (H 固定)
        ▼
┌──────────────────────────────────────────────┐
│ AEG-AEC（chunk 内）                           │
│  跟踪误差观测器 → 逆补偿 → 相位重定时         │
│  → 柔顺轨迹整形 → 安全收尾                    │
└──────────────────┬───────────────────────────┘
                   │ 下一段观测
                   ▼
┌──────────────────────────────────────────────┐
│ AEG-V（chunk 边界）                           │
│  轻量成功预测/风险门控 → 继续/回退/换恢复原语 │
└──────────────────┬───────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│ AEG-BMS（episode 级）                         │
│  SOC/SOH/SOP → 继续/重试/终局 reserve/放弃    │
└──────────────────┬───────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│ AEG-MEM（campaign 级）                        │
│  成功放置位姿 + 恢复段 + 标定指纹 + 相似度门控│
└──────────────────────────────────────────────┘
```

> 说明：AEG-BMS/AEG-MEM 是外层慢环（episode/campaign），AEG-AEC/AEG-V 是内层快环（chunk）；图中的箭头表示决策与信息流，不是严格时序。

### 2.2 AEG-BMS：成功优先的预算与重试

- **状态**：R、子任务 i、成功信念 b、重试次数 k、SOH c、RTT/jitter。
- **动作**：continue / retry-subtask / re-grasp / terminal-go / abort。
- **目标**：最大化 P(success within R)，字典序优先；步骤分只作为 tie-break 的次级目标。
- **hazard 模型**：用离线 replay + 调试槽数据训练一个轻量分类器（逻辑回归/GBDT），特征包括 chunk 方差、跟踪误差趋势、已花时间/演示中位数、重试次数、接触相位、视觉 grounding 置信度。
- **DP**：V_i(R,b)=max_a [p_a·V_{i+1}(R−τ_a,b′)+(1−p_a)·V_i(R−τ_a,b″)]，超时为吸收失败；重试条件必须满足 R−τ_retry ≥ r_term+μ_term。
- **终局 reserve**：默认 15s；长程任务 25s；由调试槽实测终局段 +5s 标定。终局 reserve 是硬约束，不允许被前面的重试吃掉。

### 2.3 AEG-AEC：chunk 内的自适应控制

- **跟踪观测器**：`e = q_cmd(t−Δ) − q_obs(t)`；RLS 估计 `q_obs ≈ g·q_cmd + b − f·sign(q̇)`；逆补偿 `q*_cmd=(q_des−b+f·sign(q̇))/g`，带 deadband 与速率限幅。
- **相位重定时**：相位分类器 φ∈{free, approach, contact, settle}；空间步长比例 free 1.2×、approach 1.0×、contact 0.5×、settle 0.3×；端点保持，速度/加速度限幅。
- **柔顺整形**：插入类在接触相位叠加 1–3mm 螺旋/侧向搜索；堆叠类最后 2cm 降速；拉链类用小幅往复维持张力；跟踪误差超阈值时回退到安全 via-point。
- **安全收尾**：每个 chunk 末段回到安全姿态；RTT>150ms 或 jitter>50ms（初值）时降速 0.7×、缩短空间步长；动作规律性保持稳定，避免触发平台的「不规则交互」记录。
- **边界**：不改 `action_chunk_size`，不假设有力矩/阻抗接口；所有参数先给初值，调试槽校准。

### 2.4 AEG-MEM：把成功变成可检索的战役记忆

- **键**：任务 id + 语言嵌入 + 场景图（物体/容器相对位姿）+ 泛化条件估计。
- **值**：容器系成功放置位姿、接近方向、释放高度、settle 时间、恢复段、机器人 id/标定指纹。
- **检索**：top-k 余弦相似度 + 门控；最大相似度低于 τ 时回退到策略自身，不做迁移。
- **位姿迁移**：`p_target = p_container + R_container·Δp_mem`；用中位数+MAD，MAD 过大时改用伺服收尾而不是直接迁移。
- **充放电**：成功 +1、失败 −1，按 campaign 衰减；相似度门控防止负迁移。
- **合规开关**：默认只用离线演示记忆；跨 episode 在线记忆需规则确认（单模型、是否允许 test-time adaptation），未确认前关闭。

### 2.5 AEG-V 与 AEG-T：保留与探索

- **AEG-V（保留）**：chunk 边界的轻量成功预测器，输入当前观测+候选 chunk 的预测末态，输出风险分；高风险时回退到保守 chunk（更慢、更小步、安全收尾）。参考 CheckVLA/PAV（[S23][S30]），但只做边界验证，不做 mid-chunk。
- **AEG-T（探索）**：把剩余时间比例 τ=R/180 作为策略输入 token，训练时随机化预算（30–180s），让策略在 τ 低时优先终局。参考 Time-Aware Policy Learning（[S25]）的 +48% 效率；风险是策略学会「赶时间」而牺牲成功率，必须用成功优先的奖励/筛选。

### 2.6 与第 7 轮的关系

- **保留**：GPR-VLA 主干、SSG 评分步骤图、PGL 放置目标阶梯、NRB 官方备注恢复库、DebugLoop 调试槽、FLEET 工程检查单。
- **升级**：OPT/ICR/SVL → AEG-MEM；第 7 轮的「放置优先」→ AEG-BMS 的终局 reserve + AEG-AEC 的接触整形。
- **新增**：AEG-BMS、AEG-AEC、AEG-V、AEG-T。
- **修剪**：把「步骤分 60%」从主论点删除；把「自适应 horizon」从主路径删除；L2L 降级；WMA-0/全任务孪生/仿真 RL 继续不做。

## 3. 可证伪点与最小实验

### 3.1 三个假设

- **H1（BMS）**：在长程/易超时任务上，成功优先的预算与重试策略能把成功率提高 2–5pp，超时率下降 30–50%。
- **H2（AEC）**：跟踪补偿+重定时+柔顺+安全收尾能把接触丰富任务（插头、网线、堆叠、拉链）成功率提高 3–8pp，跟踪误差下降 30–40%。
- **H3（MEM）**：相似度门控的成功放置位姿迁移能把放置类任务提高 1–3pp；门控失效时出现负迁移，必须能回退。

### 3.2 最小可行实验

1. **离线 replay**：用 33k 演示做 held-out，模拟 180s 预算、RTT 50–300ms、执行器 bias/gain 漂移；比较 BMS/AEC 开关的成功率、超时率、平均耗时。
2. **调试槽 A/B**：T10 插充电器、T27 叠三碗、T19 拉拉链、T16 折毛巾；每任务 10–20 次，配对比较。调试槽不计分，但能给真机反馈。
3. **full eval**：320 次 trial；按 task 做 cluster bootstrap；预先注册主要指标（成功率）与次要指标（超时率、步骤分、跟踪误差、重试次数）。

### 3.3 失败条件（提前写死）

- hazard 模型校准差 → BMS 过早放弃或该救不救；回退到固定规则（终局 reserve + 最多 1 次重试）。
- 重定时导致抖动/振荡 → 关闭 contact 段重定时，只保留跟踪补偿与安全收尾。
- 记忆负迁移 → 提高相似度门控 τ，或退回离线演示记忆。
- 规则不允许跨 episode 记忆 → 关闭 AEG-MEM 在线部分，只保留离线位姿统计。
- 固定 chunk 的执行语义不支持空间重采样 → AEC 只做跟踪补偿+安全收尾，放弃重定时。
- 策略本身到不了终局（抓取/ grounding 失败）→ AEG 无法救；此时回到模型侧，不继续加治理层。

## 4. 风险与合规

- **规则未读部分**：外部数据/仿真是否允许、跨 episode 记忆是否算在线学习、调试槽次数与成本、步骤分聚合公式，仍未核实（手册第二章 2.2 之后未读到）[S6][S7][S36]。
- **单模型合规**：AEG 的学习组件必须能解释为「同一提交系统的一部分」；默认把 hazard/verifier 做成确定性代码或小型模块，必要时折进唯一 checkpoint；AEG-MEM 默认离线。
- **无力度/阻抗接口**：柔顺是轨迹级，不是力控；插入任务的成功上限受策略本身限制。
- **延迟与动作规律性**：远程 API 会记录 RTT、jitter、动作规律性；AEC 的降速/重定时不能变成不规则抖动。
- **时间预算的反直觉**：成功优先意味着「该救就救」，但终局 reserve 不能被重试吃掉；BMS 的硬约束比 hazard 模型更重要。
- **统计功效**：320 次 trial 的 CI 约 ±5pp；不要把 1–2pp 的离线差异当结论，必须配对/分层。

## 5. 一句话押注

**在成功率优先、180 秒硬预算、固定 chunk 的 UniBot 里，最值得押注的不是更大的 VLA，而是包在冻结 VLA 外面的 AEG 执行治理层：用 AEG-BMS 把剩余时间当 SOC/SOH/SOP 做成功优先的重试预算，用 AEG-AEC 在 chunk 内做跟踪补偿/重定时/柔顺/安全收尾，用 AEG-MEM 把跨回合成功放置位姿与恢复段变成可检索的战役记忆。**

## 0. 产物摘要

**一句话**：UniBot 的真实瓶颈不是「再训一个更大的 VLA」，而是「冻结 VLA 在 180 秒硬预算、固定 chunk、接触丰富终局下的执行治理」。AEG 用 BMS 决定「要不要救」、用 AEC 决定「怎么救」、用 MEM 决定「从哪次成功里救」。

| 组件 | 作用 | 预期收益（保守） | 成本 | 状态 |
|---|---|---|---|---|
| AEG-BMS | episode 级 SOC/SOH/SOP、重试预算、终局 reserve | 长程/易超时任务 +2–5pp；超时率 −30–50% | 低（纯代码 + 轻量 hazard 模型） | 主押注 |
| AEG-AEC | chunk 内跟踪补偿、重定时、柔顺整形、安全收尾 | 接触丰富任务 +3–8pp；跟踪误差 −30–40% | 中（真机标定 + 调试槽） | 主押注 |
| AEG-MEM | 跨回合成功放置位姿、恢复段、标定指纹 | 放置类 +1–3pp；负迁移可控 | 中（离线统计 + 相似度门控） | 保留升级 |
| AEG-V | chunk 边界轻量成功预测/风险门控 | 失败前回退 +1–3pp | 低–中（小模型/规则） | 保留 |
| AEG-T | 剩余时间 token 的时间条件化策略 | 效率 +20–40%，成功率不降 | 中（小 adapter/重训） | 探索 |

**与第 7 轮的差异**：

1. **排名算术修正**：成功率优先，步骤分 tie-break，再提交时间；第 7 轮的「放置占 60% 步骤分」不再作为主论点。
2. **榜单打假**：8 个模型 × 32 任务的 29.7% 是 `gen_leaderboard.py` 生成的占位；真实代理看 RoboChallenge Table30（头部 50–64%，通才 17–45%）。
3. **约束修正**：`action_chunk_size` 固定、无 mid-chunk replan；自适应 horizon 论文不能直接用，改为 chunk 内整形。
4. **主押注转移**：从「更大的 VLA / 更多检索」转到「冻结 VLA 外面的执行治理层」。
5. **保留**：GPR-VLA 主干、SSG、PGL、NRB、DebugLoop、FLEET 工程检查单；**降级**：L2L、TLE/ACP/GF 数据引擎、全任务孪生/仿真 RL。

**Kill criteria（提前写死）**：

- 真实规则确认是「成功率+步骤分加权」而非字典序 → BMS 仍有用，但 AEC/MEM 的收益要重算。
- 调试槽显示策略本身到不了终局（抓取/grounding 失败率 >50%）→ AEG 无法救，回到模型侧。
- AEC 重定时导致振荡/动作规律性异常 → 关闭重定时，只保留跟踪补偿 + 安全收尾。
- 跨 episode 记忆被规则禁止 → AEG-MEM 退回离线演示记忆。
- 320 次 full eval 的配对实验看不到 ≥2pp 的成功率增益 → 不把 AEG 当主贡献，降级为工程优化。

### 1.3 API v2：固定 chunk 是硬约束

`unibot_submission` README（[S8]，v2，仓库最近提交 2026-08-21）要点：

| 字段/接口 | 含义 | 对 AEG 的影响 |
|---|---|---|
| `action_chunk_size` | handshake 固定；`get_action` 在整段 chunk 执行完后才再次调用 | **不能 mid-chunk replan；不能改 horizon** |
| `control_space` | `joint` 或 `ee`，二选一 | AEC 可在关节或 EE 空间做补偿；不能混用 |
| `obs_delta_indices` | 键决定传哪些观测；值决定每键堆叠帧 | 观测裁剪/时序堆叠可控；延迟与显存可控 |
| `image_resize` | 每路分辨率可指定 | 可在精度/延迟间折中 |
| `token` | 双处校验 | 工程要求 |
| 观测 | 4 路 RGB（head stereo L/R + wrist L/R，480×640）、双臂关节/EE base 位姿、夹爪、lower_body、语言单字符串 | 无语义分割/力/力矩；AEC 只能用跟踪误差做接触代理 |
| 动作 | 关节目标（7+7）或 EE 位姿（6+6）+ 夹爪 + pivot | **无刚度/阻抗/力矩指令**；柔顺只能是轨迹级 |
| N 端口 | 多机器人并发，每端口独立状态 | 服务必须无共享可变状态；AEG 记忆要按端口隔离 [S38] |
| 延迟/规律性 | RTT、延迟稳定性、动作规律性会被记录 | AEC 的降速/重定时不能变成抖动 |

**结论**：AutoHorizon、AAC、GeoAAC 等（[S26]–[S28]）「在 chunk 边界改 horizon/触发重规划」的方法不能直接移植；能做的只有 chunk 内轨迹整形、chunk 边界验证/记忆/预算。

## 2. 评分算术：成功优先，时间是硬预算

### 2.1 排名是字典序，不是加权和

设任务 t 的第 r 次 trial 成功指示为 `s_{t,r} ∈ {0,1}`，步骤分为 `p_{t,r} ∈ [0,100]`：

```text
S = (1/32) Σ_t (1/10) Σ_r s_{t,r}          # 总平均成功率
P = (1/32) Σ_t (1/10) Σ_r p_{t,r}          # 总平均步骤分
rank_key = (-S, -P, submission_date)        # 字典序
```

因此：

- **S 是第一目标**；P 只在 S 完全相同时才被比较。
- 320 次 trial 的 S 粒度是 `1/320 = 0.3125pp`；两个模型 S 相同的概率不低，但也不高。
- P 的增益不能补偿 S 的下降。第 7 轮「放置占 59.7% 步骤分」不应再被解释为「59.7% 的排名权重」。

### 2.2 320 次 trial 的统计噪声

在 S≈0.30、n=320 时：

```text
SE = sqrt(0.30 × 0.70 / 320) ≈ 0.0256
95% CI ≈ ±5.0pp
```

但 10 次运行/任务高度相关（同一任务、同一机器人、同一场景族），有效样本量 `n_eff < 320`。**正确做法**：按 task 做 cluster bootstrap；预先注册主要指标；不要把 1–2pp 的离线差异当结论。

### 2.3 180 秒是硬预算

- 单次 trial 最大 180s；超时 = 失败。
- HangCup 演示中位数约 5.9s（177 帧 @30fps），但长程任务可能几十秒。
- 失败恢复会消耗大量时间：一次重抓 + 重放可能 10–30s；两次失败的重试就能吃掉终局 reserve。

**成功优先的含义**：只要还有成功概率，时间就该花；提前完成不直接加分。BMS 的目标不是「省时间」，而是「把时间花在提高成功概率的地方，并保证终局有钱花」。

### 2.4 步骤分的正确位置

- 步骤分是 tie-break：S 相同才看 P。
- 步骤分仍是有用的**诊断信号**：它告诉你模型走到了哪一步；但不能拿它当主目标。
- 第 7 轮的终局步骤统计（39.8% 终局、59.7% 放置类）仍然成立，但用途改为：**识别成功闸门和失败集中点**。

### 2.5 一个数值例子

假设基线 S=30.0%、P=38.0：

| 方案 | S | P | 排名结果 |
|---|---:|---:|---|
| A：成功率 +1.0pp | 31.0% | 38.0 | **高于 B**（S 优先） |
| B：步骤分 +5.0 | 30.0% | 43.0 | 低于 A |
| C：成功率 +0.3pp（约 1 个 trial） | 30.3% | 38.0 | 若实际只多 0 个 trial（S 仍为 30.0%），则 B 凭 P 反超 |
| D：成功率 −1.0pp，步骤分 +10 | 29.0% | 48.0 | **低于基线** |

结论：**先保成功率，再谈步骤分。** 任何会降低成功率的「效率优化」都不应进主路径。

### 2.6 为什么终局放置仍是靶心

- 32/32 任务的成功闸门都是终局步骤；终局失败 = 整个 trial 失败。
- 真实代理里，「步骤分不低但成功率为 0」大量出现在插入/排序/扫码/折布等终局或接触丰富任务（§1.6）。
- 终局放置/插入跨 5 个泛化轴同时出现；它不是某个轴的特例。
- 因此：**放置优先的理由从「步骤分大头」改为「成功闸门 + 失败集中点」；AEG 的 BMS reserve 和 AEC 接触整形都围绕终局。**

## 3. AEG 架构

### 3.1 设计原则

1. **成功优先**：所有决策以 P(success within 180s) 为第一目标；步骤分只记录，不优化。
2. **冻结 VLA**：主模型不改权重；AEG 是外挂治理层，学习组件尽量小、可解释、可关闭。
3. **chunk 是控制单元**：不改 `action_chunk_size`；在 chunk 内做空间重采样/跟踪补偿/安全收尾，在边界做验证/记忆/预算。
4. **时间是预算**：SOC/SOH/SOP 的 BMS 语言；终局 reserve 是硬约束。
5. **记忆是非参数化的**：成功位姿/恢复段/标定指纹用检索，不用梯度；默认离线，在线需规则确认。
6. **失败安全**：任何不确定时回退到保守 chunk/安全姿态；不为了步骤分冒险。

### 3.2 AEG-BMS：episode 级预算与重试

#### 3.2.1 状态与动作

```text
状态：
  R      剩余秒数（SOC = R/180）
  i      当前子任务（来自 SSG）
  b      当前子任务成功信念（hazard 模型输出）
  k      当前子任务重试次数
  c      SOH ∈ [0,1]（标定质量）
  l      RTT/jitter（热降额）
动作：
  continue        继续当前子任务
  retry-subtask   从安全 pre-pose 重试当前子任务
  re-grasp        开爪、后退、重抓
  terminal-go     直接进入终局
  abort           安全早停（失败，但保护硬件）
```

#### 3.2.2 目标

```text
maximize  P(success within R)
subject to  R − τ_action ≥ r_term + μ_term   （终局 reserve 硬约束）
secondary:  expected step score（仅用于 tie-break 记录）
```

#### 3.2.3 hazard 模型

轻量分类器（逻辑回归/GBDT）预测「当前子任务在下一个 chunk 后成功」的概率：

| 特征 | 含义 |
|---|---|
| chunk 方差/熵 | 策略不确定性 |
| 跟踪误差趋势 | 执行器/接触异常 |
| 已花时间 / 演示中位数 | 进度是否异常 |
| 重试次数 k | 边际收益递减 |
| 接触相位 φ | free/approach/contact/settle |
| 视觉 grounding 置信度 | 目标是否找对 |
| 夹爪状态/物体可见性 | 抓取是否稳 |
| SOH c / RTT | 系统健康度 |

训练数据：离线 replay（成功/失败/扰动）+ 调试槽真机数据。输出 `p_i`，并用 Beta 校准（Platt/isotonic）。

#### 3.2.4 DP

子任务图来自 SSG（2–5 步/任务），状态空间小：

```text
V_i(R, b, k) = max_a [
    p_a · V_{i+1}(R − τ_a, b′, k′) +
    (1 − p_a) · V_i(R − τ_a, b″, k′)
]
# k′ = k+1 if a 是重试/重抓，否则 k′=k
V_N(R) = 1  if R ≥ 0          # 终局成功
V_i(R) = 0  if R < 0          # 超时失败
```

离散化：R 以 1s 为桶（0–180），k∈{0,1,2,3}，i≤5；总状态约 32×5×181×4 ≈ 116k，可实时查表/在线前向。BMS 的状态估计语言借用电池 SOC/SOH/SOP 的形式化 [S32]；chunk 选择可参考 BCP 的 Q-conditioned 思路 [S29]。

#### 3.2.5 终局 reserve

```text
r_term 默认 15s；长程任务（T16/T19/T31）25s
标定：调试槽实测终局段耗时 + 5s 安全边界；若只有整段演示时长，不直接冒充终局段
```

规则：

- `R < r_term + μ_term` → 禁止可选重试，直接 terminal-go。
- `R < μ_term_min` → 尝试最快安全终局；若连安全姿态都保不住，abort。
- 终局 reserve 不能被前面的重试吃掉；这是硬约束，优先于 hazard 的乐观估计。

#### 3.2.6 SOH/SOP/热降额

```text
SOC = R / 180
SOH = c = f(跟踪误差基线, 夹爪迟滞, 相机外参漂移, TCP 偏差)
SOP = v_max(c, φ) = v_nom · c · phase_factor(φ)
phase_factor: free 1.2, approach 1.0, contact 0.5, settle 0.3
thermal derating = g(RTT_p95, jitter)
```

- SOH 低 → 降低 SOP、增加重试预算、缩短 chunk 空间步长。
- RTT/jitter 高 → 降速、安全收尾、避免大动作。
- SOH 由 AEG-MEM 的标定指纹维护；每个端口/机器人独立。

#### 3.2.7 伪代码

```python
def bms_step(R, i, b, k, c, rtt):
    if R <= 0:
        return "timeout"
    if i == terminal and R < mu_term(i, c):
        return "terminal_fast"
    if R < r_term(i) + mu_term(i, c):
        return "terminal_go"
    p_retry, tau_retry = hazard.retry(i, b, k, c)
    if (R - tau_retry >= r_term(i) + mu_term(i, c)
            and p_retry > p_continue(i, b, c)
            and k < K_MAX):
        return "retry"
    return "continue"
```

### 3.3 AEG-AEC：chunk 内的自适应控制

#### 3.3.1 为什么是 chunk 内

API 不允许 mid-chunk replan；策略在 H 步内开环。AEC 只能在**发送前**整形 chunk，在**接收后**用跟踪误差更新模型。它不改变 horizon，只改变 chunk 的**空间采样、速度分布、接触行为和收尾姿态**。

#### 3.3.2 跟踪误差观测器

```text
e(t) = q_cmd(t − Δ) − q_obs(t)
q_obs ≈ g · q_cmd + b − f · sign(q̇)
RLS: θ = [g, b, f]ᵀ
θ ← θ + K (q_obs − φᵀθ),  K = Pφ / (λ + φᵀPφ),  P ← (P − KφᵀP)/λ
逆补偿: q*_cmd = (q_des − b + f · sign(q̇)) / g
```

- λ=0.98（遗忘因子）；θ 限幅；deadband 防抖。
- Δ 用 chunk 边界的时间戳对齐；若观测延迟未知，用 RTT/2 近似。
- 作用：执行器 bias/gain、负载变化、关节编码器 offset、摩擦；对应 Self-Adaptive VLA 的硬件偏移适应 [S22]。

#### 3.3.3 相位重定时

```text
输入：策略 waypoints x_0..x_H，相位 φ ∈ {free, approach, contact, settle}
输出：H 个目标，端点保持
空间步长比例：
  free     1.2×
  approach 1.0×
  contact  0.5×
  settle   0.3×
约束：关节速度/加速度限幅；接触段不跳点；末端安全 via-point
```

因为 chunk 的**执行时长固定**，「慢」= 每个 action 走更小的空间增量；覆盖同样距离需要更多 chunk。180 秒预算允许这种交换；AEC 的职责是**把时间花在接触段**，而不是全程慢。RoboPace 的接触感知重定时报告 64% vs 44%、时间约减半 [S21]；这里只借用相位变速思想，不改 chunk 大小。

#### 3.3.4 柔顺轨迹整形（行为级，非力控）

没有力矩/阻抗接口，只能用轨迹级技巧：

| 任务类型 | 整形 | 触发 |
|---|---|---|
| 插入（T10/T26） | 1–3mm 螺旋/侧向搜索；遇阻回退 2mm 再试 | 跟踪误差 > e_contact 或进度停滞 |
| 堆叠（T27/T25） | 最后 2cm 降速；释放后停 0.5s 再撤 | 接近目标高度 |
| 拉链（T19） | 小幅往复维持张力；卡住时回退 1cm | 跟踪误差/进度停滞 |
| 折布/软物（T16） | 抓点后慢拉；分段确认 | 夹爪负载/跟踪误差 |
| 扫码/对位（T30/T12） | 小步对准；失败后退回观察位 | 视觉置信度低 |

明确：**这是行为级柔顺，不是阻抗控制**；成功上限受策略本身和硬件低层控制限制。

#### 3.3.5 安全收尾与延迟

```text
每个 chunk 的最后 3–5 个 action → 安全 via-point
RTT_p95 > 150ms 或 jitter > 50ms（初值，待调试槽校准）：
  v_scale = 0.7
  spatial_step *= 0.7
  tail = safe_retreat(5mm)
```

- 安全 via-point：插入前退 5mm、堆叠后停住、抓取后抬到安全高度。
- 动作规律性：避免忽快忽慢/大跳变；AEC 的降速是平滑的，不是随机抖动。
- 若延迟极端（>500ms），只发「保持+微调」chunk，不做大位移。

#### 3.3.6 伪代码

```python
def aec_shape(chunk, obs, phase, c, rtt):
    theta = observer.update(obs.q_cmd, obs.q)
    chunk = observer.compensate(chunk, theta)
    chunk = retime(chunk, phase, c)
    chunk = compliance_shape(chunk, phase, obs.tracking_error)
    chunk = safe_tail(chunk, phase, rtt)
    return clip_velocity_accel(chunk)
```

### 3.4 AEG-MEM：战役记忆

#### 3.4.1 记忆模式

```text
key   = (task_id, language_embedding, scene_graph, axis_estimate)
value = {
  placement_pose_in_container,   # 位置 + 姿态
  approach_dir, release_height,
  settle_time, recovery_segment,
  robot_id, calibration_fingerprint,
  success_count, attempt_count
}
```

#### 3.4.2 检索与门控

```text
sim = cosine(key, key_mem)
if sim < τ_key: fallback to policy
top-k = 3..5
```

- τ_key 初值 0.75；按任务校准。
- 场景图用物体/容器相对位姿，不用全局外观（抗背景轴）。
- 语言用 160 条复述的嵌入（32×5）；同义复述映射到同一任务。

#### 3.4.3 放置位姿迁移

```text
p_target = p_container + R_container · Δp_mem
R_target = R_container · R_delta_mem
Δp_mem = median({Δp_i}),  dispersion = MAD({Δp_i})
if dispersion > τ_disp: use servo instead of direct transfer
```

- 只迁移**相对容器坐标系**的位姿，不迁移绝对坐标（抗位置轴）。
- 释放高度/接近方向也迁移；MAD 大时改为闭环伺服。
- 这是第 7 轮 OPT/PGL 的合并版。

#### 3.4.4 置信度与充放电

Retrieve-then-Steer 的在线成功记忆在长程任务上报告 +12.5pp [S24]；这里采用「离线优先 + 相似度门控」的保守版本，避免跨 episode 规则风险。

```text
confidence = (successes + 1) / (attempts + 2)   # Beta(1,1) 先验
decay per campaign: 0.95
on success: successes += 1; store/refresh entry
on failure: attempts += 1; if confidence < τ_conf: demote entry
```

- 相似度门控 + 置信度门控双保险，防负迁移。
- 连续两次失败 → 该条目降级，不再直接迁移。

#### 3.4.5 合规开关

- **默认离线**：只用官方 33k 演示的放置位姿统计 + 公开备注恢复段。
- **在线可选**：跨 episode 存储本次评测的成功位姿；需确认规则是否允许 test-time adaptation/单模型约束。
- 若规则不允许，AEG-MEM 仍可作为「离线先验」使用，不影响主路径。

### 3.5 AEG-V：chunk 边界验证

- 输入：当前观测 + 候选 chunk 的预测末态（EE 位姿/夹爪/物体相对位姿）。
- 输出：风险分/成功概率；高风险 → 保守 chunk（降速、小步、安全收尾）或恢复原语。
- 训练：离线 replay 的成功/失败 + 扰动；小型 MLP/GBDT；推理 <30ms。
- 参考 CheckVLA 的执行时验证 + latency-aware hard prefixing [S23]、PAV 的 prefix 判断 [S30]；但不做 mid-chunk，只做边界。
- 若延迟预算不够，直接关闭，回退到 BMS 的保守规则。

### 3.6 AEG-T：时间条件化策略（探索）

- 输入增加 `τ = R/180` 的 token/embedding；训练时随机化预算（30–180s）。
- 目标：τ 低时策略优先终局/收敛，而不是继续探索。
- 证据：Time-Aware Policy Learning 把剩余时间作为输入，效率 +48%，成功率不降 [S25]。
- 风险：策略学会「赶时间」导致成功率下降；必须用成功优先的筛选/拒绝采样。
- 实现：小 adapter/LoRA 或输入 token；若规则要求单 checkpoint，折进唯一模型。

### 3.7 集成伪代码

```python
for episode in range(320):
    obs = env.reset()
    R, i, b, k = 180.0, 0, prior[i], 0
    c = mem.calibration(robot_id)
    while R > 0:
        chunk, aux = policy.get_action(obs, language)
        chunk = aec.shape(chunk, obs, phase=i, c=c, rtt=obs.rtt)
        if verifier.risk(obs, chunk) > tau_v:
            chunk = aec.conservative(chunk)
        env.execute(chunk)
        obs = env.observe()
        R -= obs.elapsed
        b = hazard.update(obs, chunk, b)
        cmd = bms.step(R, i, b, k, c, obs.rtt)
        if cmd == "retry":
            chunk = mem.recovery(task, i, obs)
            k += 1
        elif cmd == "terminal_go":
            i = terminal
        elif cmd == "abort":
            break
        if predicate.success(obs):
            mem.store(task, obs, success=True)
            break
```

### 3.8 接口工程

| 事项 | 做法 |
|---|---|
| `action_chunk_size` | 提交前固定；按任务/机器人选择（短任务小 chunk 提反应，长任务大 chunk 提吞吐），但一旦 handshake 不可变 |
| `obs_delta_indices` | 只传必要键；腕部相机高帧、头部相机低帧；控制延迟 |
| `image_resize` | 头 480×640，腕 240×320（按策略训练分辨率） |
| `control_space` | 优先 EE（放置位姿迁移直接落）；关节空间作为回退 |
| N 端口 | 无共享可变状态；每端口独立 AEG 状态/记忆；连接池/健康检查 |
| 延迟 | 记录 RTT p50/p95/jitter；AEC 降速；避免不规则 chunk |
| 动作规律性 | 平滑限幅；不随机跳变；安全收尾 |
| token | 双处校验；日志脱敏 |

## 4. 训练与数据

### 4.1 冻结 VLA，训练小模块

| 模块 | 训练方式 | 数据 | 成本 |
|---|---|---|---|
| hazard | GBDT/逻辑回归 + 校准 | 离线 replay + 调试槽 | 低 |
| 跟踪观测器 | RLS，无梯度 | 真机/回放 | 极低 |
| AEG-V | 小 MLP/GBDT | replay 成功/失败 + 扰动 | 低 |
| AEG-T | 小 adapter/LoRA（可选） | 演示 + 时间预算增广 | 中 |
| AEG-MEM | 非参数检索 | 33k 演示 + 成功 episode | 低 |

**原则**：主 VLA 不改权重；所有学习组件可关闭；单模型合规审查。

### 4.2 hazard 数据

- 正样本：演示中成功的子任务段。
- 负样本：扰动/中断/超时/失败回放。
- 特征：chunk 方差、跟踪误差、进度、重试、相位、视觉置信度、SOH/RTT。
- 校准：Platt/isotonic；按任务分层；调试槽在线更新。

### 4.3 跟踪观测器

- 用真机/回放的 `q_cmd`、`q_obs` 估计 g/b/f。
- 注入人工 bias/gain/friction 做单元测试。
- 每个机器人/端口独立参数；AEG-MEM 存标定指纹。

### 4.4 时间条件化

- 训练时把 episode 预算随机化为 30/60/90/120/180s；标签仍是成功。
- 推理时 τ=R/180；低 τ 时策略应收敛到终局。
- 先用小 adapter 验证，不阻塞主路径。

### 4.5 放置记忆

- 从 33k 演示提取「容器系释放位姿」：位置、姿态、接近方向、释放高度、settle 时间。
- 按任务/容器/语言聚类；中位数 + MAD。
- 检索键用场景图相对位姿，不用全局外观。

### 4.6 恢复数据

- 官方 `generalization` 备注（human_1/human_4/unseen_object_3）→ 恢复段剧本（NRB）。
- 人为干扰：平移物体、撤销步骤（先叠后撤、拉链拉开、拧回瓶盖）。
- 恢复段作为 AEG-MEM 的 value，不训练大模型。

### 4.7 不做的事

- 不做全 32 任务高保真孪生；
- 不做运行时仿真/MPC；
- 不做仿真 RL；
- 不做每任务 LoRA；
- 不把 L2L 外部数据并入训练（规则未核实）。

## 5. 实验矩阵

### 5.1 E0 离线 replay

- 数据：33k 演示 held-out；模拟 180s 预算、RTT 50–300ms、执行器 bias/gain 漂移。
- 比较：baseline / BMS / AEC / MEM / full。
- 指标：成功率、超时率、平均耗时、重试次数、跟踪误差。

### 5.2 E1 调试槽 A/B

| 任务 | 理由 | 样本 |
|---|---|---|
| T10 PlugCharger | 插入、终局、接触丰富 | 10–20 |
| T27 StackBowls | 堆叠、终局、位置轴 | 10–20 |
| T19 ZipUp | 长程、软物、拉链 | 10–20 |
| T16 FoldTowel | 长程、软物、双手 | 10–20 |

配对设计：同一初始条件/轴，AEG on/off 交替；记录 RTT/动作规律性。

### 5.3 E2 full eval

- 320 次 trial；按 task cluster bootstrap；预注册主要指标（成功率）。
- 与 baseline 的配对比较：同任务、同轴、同初始条件（若平台允许）。

### 5.4 E3 消融

| 消融 | 目的 |
|---|---|
| BMS only | 预算/重试的独立贡献 |
| AEC only | chunk 整形的独立贡献 |
| MEM only | 记忆的独立贡献 |
| full | 组合 |
| BMS w/o terminal reserve | 验证 reserve 的必要性 |
| AEC w/o tracking compensation | 跟踪补偿的贡献 |
| AEC w/o retiming | 重定时的贡献 |
| MEM w/o similarity gate | 负迁移风险 |
| verifier on/off | 验证的贡献 |

### 5.5 E4 敏感性

- RTT：50/150/300ms；
- actuator bias：0/5/10%；
- gain：0.9/1.0/1.1；
- time budget：60/120/180s；
- chunk size：小/中/大（若可配置）。

### 5.6 E5 泛化轴

- 5 轴分别统计成功率；检查 AEG 是否只在某一轴有效。
- 重点：位置轴（放置位姿迁移）、人为干扰轴（恢复段）、未见物品轴（记忆门控）。

### 5.7 指标与统计

| 指标 | 说明 |
|---|---|
| 成功率 | 主指标 |
| 超时率 | BMS 的直接目标 |
| 步骤分 | tie-break/诊断 |
| time-to-success | 效率 |
| 重试次数 | 预算行为 |
| 跟踪误差 RMS | AEC 的直接目标 |
| 动作规律性 | 平台记录 |
| 记忆命中率/负迁移率 | MEM 的直接目标 |

统计：按 task cluster bootstrap；配对 McNemar（若同初始条件）；预先注册；报告 95% CI。

### 5.8 功效

- S≈0.30、n=320：95% CI ≈ ±5pp；
- 要检测 +2pp，需要配对/分层或更多 trial；
- 因此主实验用**同任务配对**，不要用 320 次独立样本的朴素检验。

## 7. 风险、合规与开关

| 风险 | 触发条件 | 缓解 | 开关 |
|---|---|---|---|
| 排名规则歧义 | 官网「综合」vs 手册字典序 | 以手册为准；向官方确认 | 若加权，重算 BMS 目标 |

| 跨 episode 记忆违规 | 规则禁止在线适应 | 默认离线；在线需书面确认 | `MEM_ONLINE=0` |
| 无力度/阻抗 | API 只有位置/EE | 行为级柔顺；不承诺力控 | `AEC_COMPLIANCE=trajectory` |
| 固定 chunk 执行语义 | 不支持空间重采样 | 只做跟踪补偿+安全收尾 | `AEC_RETIME=0` |
| hazard 误判 | 过早放弃/该救不救 | 校准+保守回退；终局 reserve 硬约束 | `BMS_HAZARD=heuristic` |
| 重定时振荡 | 接触段抖动 | 限幅+平滑；关闭重定时 | `AEC_RETIME=0` |
| 负迁移 | 相似度门控失效 | 置信度+双次成功门控 | `MEM_GATE=strict` |
| 调试槽稀缺 | 预约不到 | 离线 replay 为主；少而精 | 每版本 1 槽 |
| 统计功效不足 | 1–2pp 差异 | 配对/分层/cluster bootstrap | 预注册 |
| 外部数据违规 | 规则不允许 | 不并入训练；只做协议设计 | `L2L=off` |
| 动作规律性异常 | 降速/重定时不规则 | 平滑限幅；记录 RTT/jitter | `AEC_SMOOTH=1` |
