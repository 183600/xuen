# 第 2 轮（UniBot 线 · 第 2 轮；本轮灵感：「移动操作」×「续航能力」）

> **延续声明**：不重新基线化。第 1 轮 UniBot-SAGE 的 U1–U12 / L1–L7 / E601–E618 与 IP-01–IP-08 全部保留为 v1；本轮只增加两个被 v1 冻结的维度——**空间（身体/基座）**与**时间（接触/系统）**——新增 U13–U24 / L8–L14 / E619–E634 / IP-09–IP-13。v1 的剪枝预案继续有效：IP-06/02/03 必保，IP-01 先过合规。
> **数据纪律**：本轮**不新增赛事事实断言**。所有榜单数字沿用 v1 已核实的 teaser 缓存（8 模型 × 32 任务，检索日期 2026-11-17）；凡涉及「基座是否可动 / pivot 是否被跟踪 / 长时程退化来自哪里」一律标为**待 E619/E624 核验**，不当作已知。

## 0. 上一轮留下的两个「被冻住的维度」

v1 把系统写成「一个固定的身体 + 一段无记忆的抓握」：
1. **身体被冻住**：v1 的 IP-05 只是 P1 的「姿态先验」，且明确写了「pivot 语义未知、收益可能为 0」；主线仍假设基座不动、`reach` 因子是给定的。于是所有「够不到 / 被遮挡 / 接近角别扭」的失败，都被错误地归因到抓取或对齐。
2. **时间被冻住**：v1 的抓握隐变量 `g_t` 是**无记忆**的（只看当前帧），没有「抓住之后还能撑多久」；预算也是「每个模块都开」，没有 episode 级、运行级的能量/热/延迟分配；更没有任何长时程退化（8 h、N 端口）的度量。

本轮的两个灵感词，恰好各解冻一个维度：**移动操作 = 空间维度**，**续航能力 = 时间维度**。

### 0.1 读法声明（严谨性前提）

「移动操作」有两种读法，必须分开：
- **字面读法**：G1 的基座/腰腿真的能移动，且评测端跟踪 `action.pivot` / `observation.state.lower_body`。这是**待核验**的，不是已知事实。
- **稳健读法**：即使基座被固定，「改变观察/操作 vantage（站位、躯干前倾、相机视角）」仍是影响可达性与遮挡的真实变量；而「移动」的收益必须先用离线数据估出上界，再决定是否投入。

本轮采用**双层读法**：字面层由 E619 零成本探测闸门控制（不可用则整层降级），稳健层（可达性上界、恢复时换视角）始终有效。这样「移动操作」不会变成空中楼阁。

「续航能力」同样有两种读法，且二者共享同一个数学结构：
- **接触续航**：抓住的物体在搬运中会不会滑、还能撑多久（生存/风险过程）。
- **系统续航**：策略在 8 h、N 端口、热累积下会不会变慢、变抖、退化（可靠性/预算过程）。

## 1. 直觉解释（先直觉，后定义）

### 1.1 「移动操作」：把「够得到」从约束变成决策变量（空间预算）

**直觉**：很多看起来像「抓取失败 / 对齐失败」的 episode，真正原因是**视角与可达性**——目标在腕部相机边缘、接近角接近关节限位、桌沿挡住下降路径、目标在身体外侧。此时最便宜的修复往往不是重训策略，而是**把身体挪 10 cm / 换个站位**。基座是**最粗粒度、最耗能、但全局杠杆最大**的执行器：它一次移动，改变的是整条手臂的可达域。

**形式化要点**：给定目标位姿 `p` 与基座位姿 `b`，定义可达/可操作裕度 `μ(o,b)`（关节限位余量、距离余量、可见性、碰撞风险的合成）。基座选择不是「导航」，而是一个**带成本的离散决策**：
`b* = argmax_b [ ΔP_succ(o,b) − λ_E·E_move(b) − λ_T·T_move(b) − ρ·risk(b) ]`。
它必须被 **VOC 闸门**管住：只有当「换站位带来的成功增益」超过能量、时间、风险成本时才移动。

**恢复语义（本轮最关键的一步）**：v1 的失败恢复只有「重抓 / 非抓取原语」；本轮增加第三种——**re-anchor（换锚点）**：不改抓法，先换视角/站位再抓。对「够不到 / 被遮挡 / 接近角差」这一类失败，re-anchor 的期望收益高于同姿势重抓，且不破坏已完成阶段。

### 1.2 「续航能力」：把「能撑多久」变成可测的生存问题（时间预算）

**直觉**：桌面任务的 episode 长达 43–45 s，搬运段占大头；物体不是「抓住就永远在」，而是会**随时间滑移**。同时，评测是 N 台真机、32 任务、数小时的连续运行，模型会**热累积、延迟漂移、显存/内存缓慢增长**。这两件事是同一个问题：**在时间轴上的失效风险与预算消耗**。

**形式化要点**：
- 接触续航：把 v1 的 `g_t` 升级为**风险过程** `h_t = P(在 t 滑移 | 撑到 t)`，生存 `S(t)=∏(1−h_s)`，并估计**剩余安全时间** `τ_slip`。动作不再只问「抓住了吗」，而问「还能撑几秒、要不要现在降加速度/重抓」。
- 系统续航：定义能量/算力/热预算 `B_t`，用**影子价格** `λ_t` 把「多用一点算力/能量」折算成成功点数；预算紧（热高、剩余能量低）时 `λ_t` 上升，自动退回低成本路径。安全盾不受 `λ_t` 影响。

**一个反直觉但重要的点**：v1 已证明「做得快没有红利」（任务内 `corr(dur,succ)≈−0.011`）。所以「续航」**不是**「更快跑完」，而是**「不退化、不掉物、不超时」**。这决定了优化对象是**尾部**（p99 延迟、掉落率、热漂移），不是均值速度。

### 1.3 合成：空间预算 × 时间预算 = 一个联合分配器

**直觉**：移动基座要花能量和时间，而能量/时间正是续航预算；反过来，前期乱花算力会让后期热降频。所以「移动」与「续航」不是两个模块，而是**同一个预算的两个投影**：
- **空间投影**：这一步要不要移动身体（花大钱换可达性）；
- **时间投影**：这一步用哪档算力、允许多大加速度（花小钱换确定性/安全性）。

**本轮的中心假设（可证伪）**：**「早移动、晚重算、运输段省电」**——
1. **早移动**：基座移动只在接触前做（信息已足够、未建立接触、风险最低）；接触后禁止移动。
2. **晚重算**：大模型算力集中在 align / insert / release（最后一环），reach / transport 用轻档。
3. **运输段省电**：搬运段用低算力 + 依滑移风险的加速度上限，既省能量又降滑移。

这个假设把两个灵感词压成一条**时空预算剖面**，而不是并列的两个创新点；它也是本轮最容易被数据推翻、因而最值得预注册检验的东西。

## 2. 量化动机（只用 v1 已核实事实 + 可复现推理）

| 观测（v1 已核实 / 本轮推理） | 数值 / 形式 | 对第 2 轮的含义 |
|---|---|---|
| 计分货币唯一：`step≈1.337·succ+0.09`，R²=0.9955 | 终态成功是唯一杠杆 | 时空预算的目标函数只能是 `P(success)`，不能是「更快/更省」本身 |
| 时长与成功无关：任务内 `corr(dur,succ)≈−0.011` | 快没有红利 | 允许「为稳而慢」；加速度上限不因耗时受罚（前提：未触截止时间） |
| 最难 6 任务全是插入/旋转/细粒度 | Plug In Ethernet 17.7 / Unlock 20.1 … | 最后一环要重算力；搬运段可省 |

| episode 43.7–45.2 s，搬运段占比大 | 时间轴长 | 滑移风险是累积量，必须建模生存而非单帧判定 |
| 官方采集 per-step 延迟波动与动作规律性 | 可信度是隐性指标 | 热/负载平滑不仅是省电，也是「可信度」 |
| **待核验**：基座/pivot 是否被跟踪 | 未知 | E619 零成本探测；不可用则 IP-09 整层降级 |

**由表得到的三个可执行推论**：
- **T4（空间有上界，先测再投）**：基座移动的收益上界 = 「固定基座下因可达性/遮挡而失败的 episode 占比」。这个比例可以在离线数据上先估出来；若很小，IP-09 直接砍。
- **T5（时间看尾部，不看均值）**：续航的目标是 p99 延迟、掉落率、热漂移斜率，而不是平均速度。
- **T6（时空耦合）**：搬运中移动基座会同时增加滑移与能量成本 ⇒「移动必须发生在接触前」不是偏好，而是由耦合项推出的约束。

## 3. 研究问题（本轮新增 Q6–Q10）

- **Q6（自由度可用性）**：评测端是否真的跟踪基座/pivot？若跟踪，其动作语义、量纲、限幅是什么？若只跟踪一部分，哪一部分可用？
- **Q7（空间收益上界）**：在固定基座下，有多大比例的失败可归因于可达性/遮挡/接近角？基座 oracle 能兑现多少？（离线可估，真机可验）
- **Q8（接触续航）**：滑移能否仅用本体信号（抓手标量、EE 位姿/速度、物体-腕相对位移）预测？时间-滑移校准是否足够好到「提前降加速度」而不误伤？
- **Q9（系统续航）**：算力级联 + 热预算能否在 8 h × N 端口下把 p99 延迟与成功率同时守住？退化斜率能否被压平？
- **Q10（时空联合）**：联合分配器是否严格优于「各模块独立开」？「早移动、晚重算、运输段省电」是否在数据上成立，还是被交互项推翻？

## 4. 设计原则（在 v1 的 P1–P6 上新增 P7–P10）

- **P7 先测量，再移动**：任何「新自由度」（基座、pivot、腰腿）在证明被评测端跟踪之前，一律按「不可用」处理，并保留零成本探测。
- **P8 预算是第一等公民**：每个在线模块必须声明其延迟/算力/能量成本与「关键相位」标签；没有成本声明的模块不得进入主线。
- **P9 续航 = 不退化，不是更快**：优化尾部指标（p99、掉落率、退化斜率），禁止用「平均更快」冒充续航。
- **P10 安全包络优先于预算**：接触中不移动基座、不突破加速度硬上限、不在低置信时强行重抓；预算器只能在安全包络内分配。

## 5. 最小可提交闭环（MVP）与退化链

**MVP = E619（自由度探测）+ IP-11（滑移生存监控）+ IP-10（算力级联与预算器）+ 通用 VLA 基线**。
理由：IP-10/IP-11 不依赖「基座可动」这个未核验前提，且直接改善尾部可靠性；E619 决定 IP-09 是否值得做。IP-09（基座/换锚点）与 IP-13（联合分配器）排在 E619/E620 之后。

**严格退化链**：
- Level-0 基座/pivot 不可用 ⇒ 关闭 IP-09，只保留「换视角」的离线建议（不执行）；
- Level-1 滑移模型置信度低（AUROC 不达标）⇒ 退回固定保守加速度上限（不依赖模型）；
- Level-2 算力级联的关键相位分类器不可靠 ⇒ 全相位用中档（L1），只保留热/预算兜底；
- Level-3 联合分配器不可用 ⇒ 退回「分模块固定预算」（IP-10 独立运行）；
- Level-4 整条新链路失效 ⇒ 退回 v1 的 SAGE 基线（安全网，永远保留）。

## 6. 预期贡献（可验收）

1. **一个「自由度可用性」的测量协议**：用零成本探测回答「基座/pivot 到底能不能用」，并给出基座移动收益的离线上界（避免全赛道在不可用自由度上内卷）。
2. **接触续航的生存模型**：把 `g_t` 从二值隐变量升级为带时间-滑移校准的风险过程，证明「提前降加速度」能在不掉成功率的前提下降低掉落。
3. **系统续航的预算器**：算力级联 + 热/延迟影子价格，给出 8 h × N 端口的退化曲线与 p99 上界。
4. **一条可证伪的时空原则**：「早移动、晚重算、运输段省电」，并用联合消融检验它是否优于独立模块。
5. **八因子失败分解**：在 v1 六因子上加入 `base` 与 `sustain`，让「够不到」和「抓住后掉了」第一次成为可归因的独立因子。

## 7. 下一轮迭代计划（深化与修剪）

- **深化**：把 IP-11 的滑移风险与 IP-09 的「接触前移动」约束合并成一个**安全包络内的时空分配器**；把 IP-12 的退化曲线接入 IP-06 的代理评测，形成「离线上界 → 真机锚点」的双层标定。
- **修剪预案**：若 E619 显示基座固定且 pivot 不被跟踪 ⇒ **整层删除 IP-09**，把资源压到 IP-10/IP-11；若 E625 的滑移 AUROC <0.7 ⇒ 滑移模型降级为固定保守加速度上限；若 E623 显示级联带来成功率下降 >1 分 ⇒ 退回单档算力 + 仅热兜底。
- **保留项**：E619（事实闸门）、IP-10（可靠性 + 可信度）、IP-11（断点直击）三项在任何情况下不砍。

## 8. 本轮最大风险

**一句话**：本轮把赌注压在「身体是可用的空间自由度、长时程退化是可优化的时间预算」上，但**这两个前提都尚未被评测端证实**——若基座/pivot 实际不被跟踪、且 8 h 退化主要来自网络与评测机而非策略，那么整个时空预算层就是**在不可控变量上做精细分配**，只会增加延迟与复杂度，反而侵蚀 v1 已经守住的终态成功率。

## 0. 本轮结论摘要

**一句话路线**：v1 解决「抓得住 + 技能路由 + 工程缝合」；v2 增加「**站得对**（空间）+ **撑得久**（时间）」，并把两者统一为一个**安全包络内的时空预算分配器**——空间上把基座/换锚点当决策变量，时间上把滑移风险与算力/热预算当生存问题。

**为什么是这个组合（全部由 v1 已核实事实推出，不引入新事实）**：

| 证据（v1） | 数值 / 形式 | 推出的设计 |
|---|---|---|
| 终态成功是唯一货币 | `step≈1.337·succ+0.09`，R²=0.9955 | 预算的目标函数只能是 `P(success)`；「更快/更省」不能单独计分 |

| 断点在最后一环 | Plug In Ethernet 17.7 / Unlock 20.1 / … | 大算力集中在 align/insert/release；搬运段可省 |
| 在线模块已达 6 个、p99 ≤105 ms | 组件相加挤压预算 | 必须有统一预算器；「全开」本身违反可信度口径 |
| episode 43.7–45.2 s，搬运段占比大 | 时间轴长 | 滑移是累积风险，必须建模生存而非单帧判定 |
| 官方采集延迟波动/动作规律性 | 可信度是隐性指标 | 热/负载平滑既是省电，也是可信度 |
| **待核验**：基座/pivot 是否被跟踪 | 未知 | E619 零成本探测；不可用则 IP-09 整层降级 |

**中心假设（预注册，可被 E628/E633 推翻）**：**「早移动、晚重算、运输段省电」**——基座移动只在接触前；大算力只在关键相位；搬运段低算力 + 依滑移风险的加速度上限。

**合规红线（继承 v1 P5）**：单一 checkpoint、单一 API 服务；不使用评测侧私有信息；基座动作只在接口确实支持时下发；不做「读题即硬编码」的分支；保留策略固有随机性，不做「拟人化」噪声。

| **IP-11** | SlipWatch 接触续航 / 滑移生存监控 | **P0** | 把 `g_t` 升级为滑移风险过程，估 `τ_slip` 并提前限加速度/重抓 | 官方数据 + 小算力 | 滑移 AUROC ≥0.80；掉落率 ↓≥30% 且成功率不降 |
| **IP-12** | LongRunBench 长时程退化曲线 | **P1** | 8 h × N 端口的退化、热、内存、端口隔离度量，接入代理评测 | IP-06 + 部署 | 退化斜率 ≤ 基线；p99 漂移 ≤10%；无串扰 |
| **IP-13** | SpaceTimeAllocator 时空联合分配器 | **P1** | 在安全包络内联合选择「移动 / 算力 / 加速度上限」，用 VOC 门控 | IP-09/10/11 | 相对独立模块 ≥ +1 分，或同成功率下成本更低 |

**v1 创新点状态**：IP-01（技能路由）仍为 P0 但先过合规；IP-02（抓握确认）P0 必保，本轮由 IP-11 做时间维扩展；IP-03（chunk 缝合）P0 必保；IP-06（代理评测）P0 必保，本轮由 IP-12 做长时程扩展；IP-04/IP-05/IP-07/IP-08 按 v1 的 P1/P2 继续。

## 2. 创新点详述

### IP-09 · BaseAnchor 换锚点 / 基座站位决策（P1，E619 闸门）

- **动机**：v1 把 `reach` 当作给定因子，于是「够不到/被遮挡/接近角差」被误归因到抓取或对齐。基座是最粗粒度的执行器：一次移动改变整条手臂的可达域；而 v1 的恢复只有「重抓 / 非抓取原语」，缺了「换视角再抓」这第三种恢复。
- **与现有方案的差异**：榜单模型普遍把基座固定（或 pivot 写常量）；我们把基座/躯干当**带成本的离散决策**，并用 **re-anchor** 作为恢复原语：不改抓法，先换 vantage 再抓。它不替代 IP-02，而是给 IP-02 增加一个「失败后换几何」的维度。
- **技术可行性**：中，且**强依赖 E619**。①先用官方 client 做零成本探测：下发一个微小 pivot/基座指令，观察 `lower_body`/EE 位姿是否响应、是否被限幅；②若可用，从官方数据构造离线可达域/可操作裕度图（关节限位、距离、可见性）；③在线只在小候选集（stay / 左移 / 右移 / 前倾 / 降高）里选；④若不可用，整层降级为「离线换视角建议」，不进入执行。
- **所需资源**：数据 = 官方数据（估计可达域与 `|F|`）；算力 = 小（候选集 + 缓存的可达域）；接口 = 仅在支持时下发基座/pivot 键。
- **落地步骤**：①E619 探测并记录语义/量纲/限幅；②离线估计 `μ(o,b)` 与空间收益上界 `|F|/N`（E620）；③实现候选集 + VOC 门控；④实现 re-anchor 恢复（接触前移动）；⑤在「够不到/被遮挡/位置泛化」任务做 A/B（E621/E622/E631）。
- **风险**：①基座不被跟踪 ⇒ 收益为 0（故设 E619 闸门与整层降级）；②移动改变相机外参/标定 ⇒ 必须用「移动后重新估计目标位姿」而非缓存；③移动耗能/耗时 ⇒ 只在接触前、且 VOC 为正时移动；④安全 ⇒ 接触/搬运中绝对禁止移动（P10）。

### IP-10 · EnduranceGovernor 算力级联 + 热/延迟预算器（P0）

- **动机**：v1 的 6 个在线组件默认全开，但 per-step 预算只有约 105 ms，且官方采集延迟波动与动作规律性来评估可信度。需要一个统一的预算器回答「这一步的算力该给谁」，并把热累积纳入考虑。
- **与现有方案的差异**：多数提交用固定模型/固定档位；我们用**相位相关算力级联**（reach/transport 用轻档，align/insert/release 用重档）+ **热/延迟影子价格**（预算紧时自动降档）+ **平滑切换**（避免档位跳变造成延迟尖峰）。
- **技术可行性**：高（工程活）。关键相位分类器可复用 v1 的 U3 相位分类器与 U4 抓握置信度；级联只是「同一 checkpoint 的不同推理路径/是否启用增强」，不改变单模型合规叙述。
- **所需资源**：算力 = 极小（调度）；数据 = 无；接口 = 无。
- **落地步骤**：①埋点采集每步延迟/负载/热代理；②定义三档 `L0/L1/L2` 与成本；③关键相位分类器 + 保守阈值（漏判率优先）；④影子价格调度 + 档位平滑（最小驻留时间）；⑤8 h × N 端口 soak（E624）。
- **风险**：①关键相位漏判 ⇒ 用高召回阈值 + 关键相位强制 `L2`；②档位切换造成延迟尖峰 ⇒ 平滑 + 最小驻留；③过度保守降成功率 ⇒ 预注册「成功率损失 ≤0.5 分」否则回退；④热模型与真机不符 ⇒ 只做相对调度，阈值由 E624 标定。

### IP-11 · SlipWatch 接触续航 / 滑移生存监控（P0）

- **动机**：v1 的 `g_t` 无记忆，只能判「此刻抓住了吗」，无法回答「搬运中还能撑多久」。episode 43–45 s，搬运段最长，滑移是累积风险；v1 最大风险恰恰是「漏判（以为抓住其实没有）把可救失败变硬失败」。时间维的滑移监控正是这个风险的直接对冲。
- **与现有方案的差异**：把抓取从**二值/单帧**升级为**风险过程**：`h_t=P(滑移|撑到 t)`、生存 `S(t)`、剩余安全时间 `τ_slip`；动作层据此**提前**降加速度/重抓/换手，而不是等掉落再恢复。
- **技术可行性**：高。标签可从官方数据自动生成：夹爪闭合后「物体相对腕部的位移/速度」突变、或物体从视野消失且 EE 未动 ⇒ 滑移/掉落事件；特征全在观测里（抓手标量、EE 位姿/速度、物体-腕相对位移、接触时长）。风险模型可用离散时间 hazard（逻辑回归/小 MLP）或 Cox 型；样本量足够（32 数据集 × ~1000 eps）。
- **所需资源**：数据 = 官方数据；算力 = 小（单卡数小时）；接口 = 纯策略内部。
- **落地步骤**：①滑移/掉落伪标 + 人工抽检；②训练 hazard + 校准（可靠性图、时间-滑移 coverage）；③定义 `τ_slip` 与加速度上限映射；④与 v1 `g_t` 融合（单帧置信 + 时间风险）；⑤在运输/插入任务做 A/B（E625/E626/E627）。
- **风险**：①伪标噪声 ⇒ 双标注器一致性 + 人工抽检；②未见物品分布漂移 ⇒ 保守阈值 + 每 episode 自校准；③过度限速影响插入对齐 ⇒ 加速度上限只作用于搬运段，align/insert 用独立精度约束；④「为稳而慢」触发截止时间 ⇒ 预算器同时看 `t_rem`。

### IP-12 · LongRunBench 长时程退化曲线（P1）

- **动机**：v1 的代理评测是**单 episode/离线**的，无法回答「跑 8 h 后还稳不稳」。官方在多台真机上连续评测，长时程退化（热降频、延迟漂移、内存增长、端口串扰）会直接侵蚀成功率与可信度。
- **与现有方案的差异**：多数队伍只测「能不能跑」；我们定义**退化曲线** `D(τ)`（成功率/p99 随运行时间的变化）与**退化斜率**，并把它作为 IP-10 的验收标尺。
- **技术可行性**：高（工程 + 统计）。需要 N 端口并发压测、状态隔离检查、热/延迟/内存采样。
- **所需资源**：算力 = 极小；数据 = 自采运行日志；接口 = 官方 client。
- **落地步骤**：①压测脚本（N 端口 × 8 h，随机任务顺序）；②采样 p50/p99 延迟、内存、热代理、降级次数；③计算 `D(τ)` 与斜率；④与真机成功率做锚点相关（E624/E629）。
- **风险**：①退化主要来自网络/评测机而非策略 ⇒ 只把「策略侧可控部分」纳入优化；②长时压测成本高 ⇒ 用缩短版（1–2 h）+ 外推，并用 E624 校准；③与真机相关性未知 ⇒ 预注册「若 |r|<0.3 则仅作监控，不作优化依据」。

### IP-13 · SpaceTimeAllocator 时空联合分配器（P1）

- **动机**：IP-09/10/11 若各自独立开，会出现「移动基座 + 搬运中高算力 + 不设加速度上限」的坏组合。空间与时间共享同一个预算，必须联合决策。
- **与现有方案的差异**：把「移动 / 算力档 / 加速度上限」放进一个**小离散动作集**，在安全包络内用 VOC 选择：`argmax [ΔP̂_succ − λ_E ΔE − λ_L ΔL − λ_R risk]`。它不是新模型，而是一层**决策器**，仍是一个 checkpoint、一个 API。
- **技术可行性**：中–高。候选集很小（如 5 基座 × 3 算力 × 3 加速度上限 = 45），在线枚举成本可忽略；关键是 `ΔP̂_succ` 的估计要保守（不确定时退回安全动作）。
- **所需资源**：算力 = 极小；数据 = 复用 IP-09/10/11；接口 = 无。
- **落地步骤**：①定义安全包络（接触中禁移、硬加速度上限、低置信不重抓）；②实现 VOC 枚举 + 保守回退；③实现「早移动、晚重算、运输段省电」剖面作为默认先验；④与独立模块做联合消融（E628/E633）。
- **风险**：①`ΔP̂_succ` 估计噪声导致错误移动 ⇒ VOC 加不确定惩罚 + 移动需超过最小增益；②联合搜索引入决策延迟 ⇒ 候选集小 + 缓存；③与 v1 的 chunk 缝合/自适应 chunk 冲突 ⇒ 在块边界统一调度，避免同时切换。

## 3. 符号与定义（U13–U24）

| 符号 | 含义 |
|---|---|
| `b_t` | 基座/躯干位姿（平面位姿 + 高度 + 躯干俯仰） |
| `a^base_t` | 基座动作 `(Δx, Δy, Δψ, Δh, Δθ)`；接口不支持时动作空间退化为 `∅` |
| `μ(o,b)` | 可操作裕度 ∈[0,1]（关节限位、距离、可见性、碰撞的合成） |
| `E_rem` | 剩余能量预算（可用延迟×功率代理） |
| `λ_E, λ_L, λ_R` | 能量/延迟/风险影子价格 |
| `l_t` | 算力档位 `∈{0,1,2}`（轻/中/重） |
| `Θ_t` | 热状态（由负载一阶滤波得到的代理温度） |
| `h_t` | 滑移风险 `P(滑移在 t | 撑到 t)` |
| `S(t)` | 接触生存概率 `∏_{s≤t}(1−h_s)` |
| `τ_slip` | 剩余安全时间（生存降到安全分位的时间） |
| `a_cap` | 依滑移风险得到的加速度上限 |
| `B_t` | 联合预算状态 `(E_rem, Θ_t, L_rem, t_rem, risk_budget)` |
| `D(τ)` | 长时程退化曲线（成功率/p99 随运行时间） |

**定义 U13（基座位姿与动作）** `b_t ∈ SE(2) × [h_min,h_max] × [θ_min,θ_max]`；`a^base_t` 为其增量。若 E619 证明评测端不跟踪，则 `a^base_t ≡ ∅`，IP-09 整层降级。

**定义 U14（可操作裕度）** `μ(o,b) = min{ min_i (q_i^max−q_i)/Δq_i, (r_max−‖p_o−p_b‖)/r_max, vis(o,b), 1−collision(o,b) } ∈ [0,1]`，其中 `q_i` 为目标 `p_o` 在基座 `b` 下的 IK 解。

**定义 U15（换锚点策略）** 若 `μ(o,b0) < μ_min` 且预算允许，则 `b* = argmax_b [ μ(o,b) − λ_E E_move(b) − λ_L T_move(b) ]`；仅当 `μ(o,b*)−μ(o,b0) > Δμ_min` 且处于接触前相位时执行。

**定义 U16（能量预算）** `E_move(b) = c_xy‖Δxy‖ + c_ψ|Δψ| + c_h|Δh| + c_step·n_steps`；`E_rem ← E_rem − E_move`；系数 `c_*` 为待标定先验（由真机日志回归）。

**定义 U17（算力级联）** `l_t ∈ {0,1,2}`，成本 `c_l = {5,60,100}` ms（先验，按实测替换），期望增益 `G_l(phase, unc)`；选择 `l* = argmax_l [ G_l − λ_L·c_l ]`。

**定义 U18（热状态与延迟）** `Θ_{t+1}=αΘ_t+(1−α)u_t`，`u_t` 为归一化负载；`L_t = L0 + k(Θ_t−Θ_ref) + ε`；当 `Θ_t > Θ_max` 触发降档（throttle）。

**定义 U19（滑移风险）** `h_t = σ(w^T φ_t)`，`φ_t = [g_t, Δg_t, ‖a_ee‖, ‖v_ee‖, ‖Δp_obj-wrist‖, contact_time, payload_proxy]`；`S(t)=∏_{s≤t}(1−h_s)`。

**定义 U20（剩余安全时间）** `τ_slip(t) = min{ Δ : S(t+Δ) < 1−q }`，`q` 为安全分位（先验 0.9）。

**定义 U21（加速度上限）** `a_cap(t) = a_max · clip((τ_slip−Δ_h)/max(τ_slip,1), α_min, 1)`，`Δ_h` 为反应时域，`α_min` 为硬下限。

**定义 U22（联合预算状态）** `B_t = (E_rem, Θ_t, L_rem, t_rem, risk_budget)`，由 IP-10/IP-12 维护。

**定义 U23（时空分配策略）** `a*_t = argmax_{a∈A} [ ΔP̂_succ(a) − λ_E ΔE(a) − λ_L ΔL(a) − λ_R risk(a) ]`，s.t. 安全包络 `S`（接触中禁移、硬上限、低置信不重抓）。

**定义 U24（退化曲线）** `D(τ) = (success(τ), p99(τ))`；退化斜率 `dD/dτ`；验收目标为 `|d p99/dτ|` 与 `|d success/dτ|` 均不劣于基线。

```python
# ===== 预算状态（每端口独立）=====
@dataclass
class Budget:
    E_rem: float
    Theta: float
    L_rem_ms: float
    t_rem_s: float
    lam_E: float = 0.0
    lam_L: float = 0.0
    lam_R: float = 1.0

    def update(self, load, latency_ms, dt, phase):
        self.Theta = self.ALPHA * self.Theta + (1 - self.ALPHA) * load
        self.L_rem_ms -= latency_ms
        self.t_rem_s -= dt
        self.E_rem -= self.energy(load, latency_ms, dt)
        # 预算越紧，影子价格越高（对偶上升的近似）
        heat = max(0.0, (self.Theta - self.T_SOFT) / (self.T_MAX - self.T_SOFT))
        time = max(0.0, 1.0 - self.t_rem_s / self.T_TOTAL)
        self.lam_L = self.LAM0 * (1 + self.K_HEAT * heat + self.K_TIME * time)
        self.lam_E = self.LAM_E0 * (1 + self.K_HEAT * heat)
```

```python
# ===== IP-11：滑移生存监控 =====
class SlipWatch:
    def features(self, obs, s):
        return torch.cat([
            obs["observation.state.left_gripper"][-1:],
            obs["observation.state.right_gripper"][-1:],
            s.dgrip,                       # 抓手开合差分
            s.ee_acc, s.ee_vel,            # 末端加速度/速度
            s.obj_wrist_rel,               # 物体-腕相对位移（几何/视觉代理）
            torch.tensor([s.contact_time, s.payload_proxy]),
        ])

    def hazard(self, obs, s):
        return torch.sigmoid(self.net(self.features(obs, s))).item()

    def tau_slip(self, obs, s, q=0.9, horizon=30):
        S = 1.0
        for d in range(1, horizon + 1):
            S *= (1.0 - self.hazard(obs, s, ahead=d))
            if S < 1.0 - q:
                return d
        return horizon

    def accel_cap(self, obs, s, a_max, react=1):
        tau = self.tau_slip(obs, s)
        frac = max(0.2, min(1.0, (tau - react) / max(tau, 1)))
        return a_max * frac
```

```python
# ===== IP-10：算力级联 + 热/延迟预算器 =====
class ComputeCascade:
    COST = {0: 5.0, 1: 60.0, 2: 100.0}          # ms，先验，按实测替换
    CRITICAL = {"align", "insert", "release"}

    def gain(self, phase, unc, level):
        # 关键相位、高不确定时，重档增益更大；否则边际收益递减
        base = 1.0 if phase in self.CRITICAL else 0.2
        return base * unc * {0: 0.4, 1: 0.8, 2: 1.0}[level]

    def choose(self, phase, unc, budget):
        best, best_voc = 1, -1e9
        for l in (0, 1, 2):
            if phase in self.CRITICAL and l < 2:
                continue                       # 关键相位强制重档（安全优先）
            voc = self.gain(phase, unc, l) - budget.lam_L * self.COST[l]
            if voc > best_voc:
                best, best_voc = l, voc
        return best
```

```python
# ===== IP-09：换锚点（E619 通过后才启用）=====
class BaseAnchor:
    def __init__(self, available, reach_map):
        self.available = available
        self.reach_map = reach_map

    def propose(self, obs, budget):
        if not self.available:
            return None
        b0 = obs["observation.state.base_pose"]
        cands = self.reach_map.candidates(b0)          # stay/左移/右移/前倾/降高
        scored = []
        for b in cands:
            mu = self.reach_map.mu(obs, b)
            cost = budget.lam_E * self.reach_map.E_move(b0, b) \
                 + budget.lam_L * self.reach_map.T_move(b0, b)
            scored.append((mu - cost, b, mu))
        best_voc, best_b, best_mu = max(scored, key=lambda x: x[0])
        mu0 = self.reach_map.mu(obs, b0)
        if best_mu - mu0 < self.DELTA_MU_MIN or budget.E_rem < self.reach_map.E_move(b0, best_b):
            return None
        return best_b
```

```python
# ===== IP-13：安全包络内的时空联合分配 =====
class SpaceTimeAllocator:
    CONTACT = {"grasp", "lift", "transport", "align", "insert", "place", "release"}

    def act(self, obs, s, budget):
        # 1) 安全包络：接触中禁止移动基座
        base = None if s.phase in self.CONTACT else self.anchor.propose(obs, budget)
        # 2) 算力档位：关键相位重算，其余按影子价格
        level = self.cascade.choose(s.phase, s.uncertainty, budget)
        # 3) 加速度上限：仅搬运段按滑移风险收紧
        a_cap = (self.slip.accel_cap(obs, s, self.a_max)
                 if s.phase == "transport" else self.a_max)
        return base, level, a_cap
```

```python
# ===== 统一策略服务（单 checkpoint、单 API；每端口状态隔离）=====
class UniBotSAGE2Policy:
    def __init__(self, ckpt, N=3):
        self.model = load_single_checkpoint(ckpt)      # v1 主干 + 专家
        self.fc = PhaseClassifier()
        self.gv = GraspVerifier()                      # v1 IP-02
        self.slip = SlipWatch()                        # IP-11
        self.cascade = ComputeCascade()                # IP-10
        self.anchor = BaseAnchor(E619_AVAILABLE, ReachMap.load())  # IP-09
        self.alloc = SpaceTimeAllocator(self.anchor, self.cascade, self.slip)
        self.st = Stitcher()                           # v1 IP-03
        self.audit = AuditLog()                        # v1 IP-08
        self.sessions = {}                             # 每端口一份 Budget/状态

    def reset(self, port=None):
        self.sessions.setdefault(port, Session()).reset()

    def get_action(self, obs, port=None):
        s = self.sessions[port]
        t0 = time.perf_counter()
        s.phase = self.fc.predict(obs)
        base, level, a_cap = self.alloc.act(obs, s, s.budget)

        if base is not None:
            a = self.pack_base(base, obs)              # 仅接口支持时
        else:
            a = self.model.act(obs, s.ztask, s.phase, s.ctx,
                               self.chunk_len(s.phase), compute_level=level)

        a = self.slip.clamp_accel(a, a_cap)            # 搬运段限加速度
        a = self.st.stitch(a, s.last_action)           # v1 C0 缝合
        a = self.audit.clamp_and_log(a, obs, t0, s.budget)  # v1 延迟兜底
        s.last_action = a[-1]
        s.budget.update(load=level / 2.0,
                        latency_ms=(time.perf_counter() - t0) * 1000,
                        dt=self.dt, phase=s.phase)
        return self.pack(a, s.phase, obs)
```

## 5. 推导（引理 L8–L14）

**引理 L8（空间收益上界）** 设 `F = {episode : μ(o,b0) < μ_min}` 为固定基座下因可达性/遮挡而失败的 episode 集合。任何基座策略只能改变 `F` 内 episode 的结果；对 `e ∉ F`，固定基座已有足够裕度，基座移动至多不改变结果。故基座策略的成功增益上界为 `|F|/N`。**推论**：先离线估 `|F|/N`（E620）；若很小，IP-09 不值得做。∎

**引理 L9（早移动占优）** 若 (i) 接触期间移动基座有非负安全惩罚，(ii) 与基座选择相关的信息在首次接触前已可获得，(iii) 移动成本只付一次且收益在后续持续，则任何「接触中/接触后移动」的策略都被「接触前移动到同一 `b*`」弱支配。**证明要点**：早移动保留同一 `b*`、避开接触风险、且不减少信息；若接触会揭示新信息（如物体重量），则条件 (ii) 不成立，结论失效。∎

**引理 L10（加速度上限不伤成功）** 在 v1 的「成功对时长不敏感」（`corr(dur,succ)≈−0.011`）且滑移风险对加速度幅值单调不减的假设下，收紧加速度上限弱降低掉落概率；只要 episode 截止时间未绑定，任务成功条件 `P(no drop)·P(task|no drop)` 的第二因子不变，故成功率不降。**推论**：`a_cap` 是「免费」的可靠性改进，唯一代价是耗时；但耗时不计分（v1）。∎

**引理 L11（算力级联的成功损失上界）** 设 `β = P(关键相位被判为非关键)`，关键相位全算力相对轻档的增益为 `ΔG`，则级联相对全重档的成功损失 `≤ β·ΔG`；平均算力节省 `≥ (1−π_crit)(c_2−c_0)`。取阈值使 `β ≤ 0.05`，则损失可控。∎

**引理 L12（热预算下 p99 有界）** 一阶热模型 `Θ_{t+1}=αΘ_t+(1−α)u_t` 的稳态 `Θ_ss = E[u]`。若平均负载 `E[u] ≤ Θ_soft < Θ_max`，则稳态不触发 throttle；负载阶跃的瞬态超调被 `(1−α)` 限制，故 `L_t ≤ L0 + k(Θ_soft−Θ_ref) + margin`，p99 有界。∎

**引理 L13（影子价格最优性）** 对可分离凹的期望成功增益与线性成本，在预算约束下的 Lagrangian 最优解等价于按 VOC 选择动作，且 `λ*` 等于预算约束的边际成功增益；预算松弛时 `λ*=0`（倾向多用），预算紧时 `λ*` 上升（倾向省用）。∎

**引理 L14（滑移可识别性）** 设运输 episode 数为 `n`、滑移事件率 `p`，则风险模型 AUROC 的估计标准误近似随 `1/√(n·p·(1−p))` 下降；要得到稳定校准（bootstrap CI 半宽 ≤0.05），需至少约 200 个滑移事件。**推论**：32 数据集 × ~1000 eps 足够；若某任务事件率过低，则只做跨任务共享模型，不单独拟合。∎

## 11. 本轮最值得押注的创新点与最大风险

**最值得押注**：**IP-11（SlipWatch）+ IP-10（EnduranceGovernor）**——它们不依赖「基座可动」这个未核验前提，却直接打在 v1 最大风险（抓握漏判 → 硬失败）与官方可信度口径（延迟稳定）上；IP-09 是高风险高回报的期权，由 E619/E620 两道闸门控制，不达标就整层砍掉，不拖累主线。

**本轮最大风险**：本轮把赌注压在「身体是可用的空间自由度、长时程退化是可优化的时间预算」上，但这两个前提都尚未被评测端证实——若基座/pivot 实际不被跟踪、且 8 h 退化主要来自网络与评测机而非策略，那么整个时空预算层就是在不可控变量上做精细分配，只会增加延迟与复杂度，反而侵蚀 v1 已经守住的终态成功率。
