# 想法区 · 第 8 轮：从 X-DUB/AG* 到 X-DUB/TQ*

**灵感词**：确定性算法 / 近似算法 / 计算几何  
**起点**：v0.5「X-DUB/AG*」。它已经有 A* 的路径最大下界 `F`、focal + 贪心 guide、THRESH 阈值证书、同 `S` 支配和证明 DAG。本轮不推翻这些，只补三个更基础的结构性缺口：**窗口证书只用了“完全被迫”的任务、状态商取得太细、近似只停留在启发式**。

## 一句话直觉：窗口不是矩形，是帐篷；只取“完全被迫”的任务，等于只取帐篷的平顶

v0.5 的 THRESH 对固定窗口 `[a,b)` 和候选截止期 `H` 做：

```text
X_H = { i : lo_i ≥ a 且 H - q_i ≤ b }
若 BP(X_H, caps) 不可行，则 H 不可行
```

这要求任务**完全**落在窗口里：`lo_i ≥ a` 且完成期限 `H-q_i ≤ b`。但一个任务只要与窗口有交叠，就对窗口内的机器容量有“强制占用”。把任务 i 的最早开始记为 `est_i`、最晚完成记为 `H-q_i`，它在窗口 `[a,b)` 内的强制处理量是

```text
e_i(a,b;H) = max(0, p_i - max(0, a-est_i) - max(0, H-q_i-b)).
```

这个函数在 `(a,b)` 平面上是一个**帐篷**：中间平顶是 `p_i`（任务完全被迫在窗口里），两条斜边是部分交叠，外面是 0。v0.5 只取了平顶 `e_i=p_i`，把斜边全扔了。斜边恰恰是低截止期、紧窗口时最有信息的部分。

更强的证书因此是：

```text
items = { e_i(a,b;H) : i∈R, e_i>0 }
caps_k = max(0, b - max(a, A_k))
若 BP(items, caps) 不可行，则不存在 makespan ≤ H 的完成。
```

为什么这是对的？取任意一条 makespan ≤ H 的完成调度。任务 i 在窗口内的那一段是 `[s_i, s_i+p_i) ∩ [a,b)`，长度至少是 `e_i`；它落在任务所在的机器上，且同一台机器上的这些段互不重叠。把每段缩到 `e_i`，就得到 `items` 到 `caps` 的一个可行装箱。所以“装箱不可行”蕴涵“调度不存在”。这是一个**单边近似**：它可能漏掉真正的不可行（假阴性），但绝不会把可行误判为不可行（无假阳性）。换句话说，**近似的是不可行区域，不是答案**；近似误差只会让下界变弱，不会让搜索剪错。

这个观察把 THRESH 从“点证书”升级成“区间证书”：

- 固定 `(a,b)`，`e_i` 随 `H` 单调不增（`H` 越小，最晚完成越早，强制段越长），所以 `BP` 不可行性对 `H` 向下封闭；
- 可以二分求 `H*(a,b) = max{H : BP(items(H),caps) 不可行}`；
- 一张证书覆盖所有 `H ≤ H*(a,b)`，给出 `L_TENT = max(L0, max_{a,b}(H*+1))`。

这和 v0.5 的 THRESH 是严格的包含关系：完全被迫的任务有 `e_i=p_i`，部分任务只会增加非负的 item；所以同一个窗口上，THRESH 能证的 TENT 一定能证，反过来不成立。一个真实的状态级例子（`pool30[0]` 的一个前缀，细节见产物区 §4.3）可以看出严格性：

```text
S={0,1,4}, A=(0,10), L0=13, U=16, OPT=15
窗口 [0,13), H*=14, caps=(13,3)
TENT items=(4,3,1,5,2,2)，总和 17>16 -> 不可行，TENT=15
THRESH 在同一窗口只看到 X={3,5,6}，items=(3,1,5) -> 可装 (3 | 1+5)，THRESH=14
```

这个例子说明“部分强制”不是装饰：THRESH 的 14 差 1，TENT 的 15 正好闭合 OPT。

## 第二个缺口：状态商 `(R,A,est)` 比 `(S,A,c)` 更粗，也更正确

v0.5 的支配是：同一个已调度集 `S` 下，`A` 逐分量更小、`c` 逐分量更小。这个条件太细。未来只通过“剩余任务的最早开始”与已调度部分发生关系：

```text
est_i = 已调度前驱的完成时间与剩余前驱链共同决定的最早开始
```

只要 `A` 和 `est` 逐分量不大于对方，任何从对方出发的动作序列，搬到己方都会每一步都不晚。因此

```text
σ ⪯_Q τ  iff  A_σ ≤ A_τ 且 est_σ,i ≤ est_τ,i (∀i∈R)
```

是可靠的，而且 `c` 支配蕴涵 `est` 支配，反过来不成立。几何上，这把状态映射成势空间 `(A,est_R)` 里的一个点，支配就是**正交象限查询**，非支配集就是 Pareto 天空线。v0.5 的 `c` 支配是在一个更细的空间里做同一件事，会漏掉“`c` 不同但 `est` 相同”的等价状态。

理论上这是严格更强的剪枝；实验上却有一个诚实的负结果：在 v0.5 的 AVAIL 点测试已经开启后，30 个困难实例上 `c` 支配是 200 次扩展，`est` 支配是 195 次（1 胜 29 平 0 负）。也就是说，**大部分“c 不同但 est 相同”的状态已经被 AVAIL 提前剪掉了**。这个改动的价值主要在状态表示、证明和 TENT 的接口，而不是节点数。这个负结果本轮照实报告，不把它包装成主卖点。

## 第三个缺口：近似算法应该近似“证书”，而不是近似“答案”

v0.5 的 focal/guide 是启发式，但没有近似保证；v0.6 把“近似”拆成两层：

1. **证书的近似（TENT）**：用独立 item 的装箱去近似“窗口内精确可行性”。它是单边的、可检查的、确定性的；近似误差只让下界变弱，答案仍然精确。
2. **支配的近似（δ-dominance）**：`A_σ ≤ A_τ+δ`、`est_σ ≤ est_τ+δ`。单次替换有引理 `OPT(σ) ≤ OPT(τ)+δ`（把 τ 的最优调度整体右移 δ 即可）。若不做预算，多次替换的 δ 会累积，最坏情况没有 `(1+ε)` 保证；把预算 `b` 并入状态、每次替换扣 δ、并用 `B=⌊εL0⌋` 限制总误差，才能得到确定性的 `U ≤ OPT+B ≤ (1+ε)OPT`。本轮实现了朴素的 δ 模式做实验：30 个实例上 141 次扩展，反而略高于精确的 139 次（k=27 从 25 降到 20，k=29 从 30 升到 37）。结论是：**近似支配不是当前瓶颈**；默认应关闭，保留为大规模/ anytime 的旋钮。

## 实验带来的三个意外

第一，**TENT 的收益集中在根节点**。30 个困难实例上，根下界 `L0` 总和 683，v0.5 THRESH 691，TENT 697；TENT 对 THRESH 是 30/30 不劣、5/30 严格更好；TENT 达到 OPT 的有 29/30，THRESH 是 25/30。根下界只多 6 个单位，但搜索扩展从 195 降到 139（6 胜 24 平 0 负，28.7%），因为多出来的 1–2 个单位正好落在最难的几个实例的根上，直接把“还要证一层”变成“根上就闭合”。

第二，**真正起作用的是“部分 item”，不是“更多窗口”**。把 TENT 的 item 放回 v0.5 的旧窗口族，根下界总和是 695；换成完整的 `(a,b)` 窗口族是 697。完整窗口族只在 2/30 个实例上再加 1–2 个单位。所以几何的贡献首先是**帐篷的斜边**，其次才是二维窗口扫描；这也解释了为什么 v0.5 的 THRESH 已经不错，却仍会在低截止期上漏掉部分强制量。

第三，**简单的“链容量”证书被 L0 支配**。我曾以为“一条优先链上的强制段总和不能超过窗口长度 `b-a`”能抓优先约束 gap；在 78 个随机状态上，它 0/78 严格优于装箱，62/78 严格更弱，且总和恰好等于 `L0`。原因是 `L0` 的最长链已经用了完整工时，窗口内的截断反而更松。这个负结果说明：**precedence gap 不是“某条链在窗口内装不下”这么简单**；要抓它，需要更强的顺序/机器耦合松弛，而不是再加一个链和。

## 本轮方案：X-DUB/TQ*

在 v0.5 上做四处增量：

1. **Q-STATE / Q-DOM**：搜索状态从 `(S,A,c)` 换成 `(R,A,est)`；支配用 `A` 与 `est` 的逐分量序；证明模拟引理；保留 `F` 继承与 focal。
2. **TENT-CERT**：固定窗口的强制段 `e_i`，做精确装箱；二分 `H*(a,b)`；一张证书覆盖 `H≤H*`；根节点/周期扫描启用，点测试可选。
3. **TENT-POINT**：在 `H=U-1` 上额外跑一次 TENT 装箱；实验只多剪 2/139 个节点，作为可选层。
4. **EPS-DOM**：`δ`-支配的单次引理与预算化 `(1+ε)` 设计；朴素模式实验无收益，默认关闭。

组合下界：

```text
L_X6(σ) = max( L0, L_D, L_AV, L_TH, L_TENT )
F(σ)    = 路径上所有 L_X6 的最大值
f(σ)    = max( C(σ), F(σ) )
```

因为同一窗口上 `L_TENT ≥ L_TH`，且 `F` 取路径最大，所以 `L_X6 ≥ L_X5`；关闭 TENT/Q-DOM 就回到 v0.5 的搜索语义。

## 本轮要验证的命题

1. **TENT 可靠**：任意可行完成在窗口内的段长 ≥ `e_i`；这些段诱导一个 `items → caps` 的可行装箱；所以装箱不可行 ⇒ H 不可行。
2. **TENT 单调**：固定 `(a,b)`，`e_i` 对 `H` 单调不增；`BP` 不可行对 `H` 向下封闭；`H*` 的二分合法。
3. **TENT 包含 THRESH**：同一窗口下，THRESH 的 item 是 TENT item 的子集；TENT 检测到所有 THRESH 检测。
4. **Q-DOM 可靠**：`A`/`est` 逐分量更小 ⇒ 任意动作序列的模拟不晚 ⇒ `OPT` 不大于。
5. **Q-DOM 包含 c-DOM**：`c` 逐分量更小 ⇒ `est` 逐分量更小；反之不成立。
6. **δ-DOM 单次可靠**：`OPT(σ) ≤ OPT(τ)+δ`；预算化后可把总误差限制在 `B`。
7. **搜索仍精确**：剪枝只用可采纳的 `f`；guide 只排序；Q-DOM 只删不优状态；终止时 `U=OPT`。
8. **实验收益**：30 个困难实例上 `Q+TENT` 的扩展数应显著低于 `Q`；所有变体的 `U` 必须等于独立 DFS 的 OPT；TENT 不能产生假证书。

## 初步结果与边界

- **根下界**：30 个困难实例，`L0` 总和 683，THRESH 691，TENT 697；TENT≥THRESH 30/30，严格 5/30；TENT=OPT 29/30，THRESH=OPT 25/30；装箱测试 965 → 3135，总耗时约 0.02 秒（纯 Python，30 个实例）。
- **搜索**：同一 harness 下，`c` 支配 + AVAIL 是 200 次扩展，`est` 支配 + AVAIL 是 195 次，`est` + 根 TENT 是 139 次，再加 TENT-POINT 是 137 次。`est` + 根 TENT 对 `est` 是 6 胜 24 平 0 负；对 `c` 支配是 6 胜 24 平 0 负（总计少 30.5%）。所有变体 30/30 返回 OPT。
- **逐实例**：k=6 从 3→1，k=11 从 38→11，k=13 从 1→0，k=14 从 8→5，k=19 从 7→2，k=27 从 43→25（加 TENT-POINT 23），k=29 从 30→30（根下界 34，OPT=35，容量证书关不上最后 1 个单位）。
- **窗口消融**：TENT 用旧窗口 695，用完整窗口 697；完整窗口只在 k=27、k=29 上各加 1。
- **状态级**：78 个随机可达状态，`L0` 总和 1685，THRESH 1872，TENT 1912；TENT≥THRESH 78/78，严格 30/78；装箱测试 3149 → 10291。
- **验证**：40 个随机实例、118 个 TENT 声明，逐一用独立的有界 DFS 检查，0 个假阳性；60 个新鲜 n=9 实例上 TENT 从不超过 OPT；其中只有 3 个实例 `L0<OPT`，TENT 在 1/60 上严格优于 THRESH，0/60 更差。
- **近似**：δ=1 的朴素支配 141 次（k=27 25→20，k=29 30→37），相对精确 139 次无净收益；单次替换引理成立，但全局 `(1+ε)` 需要预算化状态，本轮未实现。
- **负结果**：链容量证书在 78/78 个状态上不优于 TENT 装箱，62/78 严格更弱，总和等于 L0；周期 TENT 在 n≤10 上没有触发（节点数 <40），留给更大规模。
- **边界**：m=2、n=9–10、30 个筛选出的困难实例；没有 PSPLIB、没有 m>2 的精确装箱、没有独立 proof-DAG checker、没有 n≥20 的 anytime 曲线。时间只用于相对 sanity check。

## 本轮的一句话最大风险

**TENT 的收益集中在根节点、低截止期、容量–截止期耦合的困难尾部；在 precedence-heavy 或 m>2 的大实例上，窗口枚举与精确装箱的成本可能超过它省下的节点，而它对纯顺序 gap（k=29 的 L=34 vs OPT=35）仍然无能为力。**

# 产物区 · v0.6：X-DUB/TQ*

> Tent-packing certificates with quotient dominance and deterministic search  
> 中文名：帐篷强制段打包 + 势商支配 + 确定性搜索  
> 状态：完整设计稿；30 个 n=9–10 困难随机 DAG 的根下界/节点数/消融、78 个随机状态的阈值对比、118 个 TENT 声明的独立 DFS 验证已完成；m>2 精确装箱、独立 proof-DAG checker、PSPLIB 规模实验留到下一轮。

## 0. 版本关系与本轮增量

v0.5（X-DUB/AG*）已经建立：

- `P|prec|Cmax` 的 `(任务,机器)` 动作空间与最优性覆盖；
- 路径最大下界 `F`、一致启发式 `f=max(C,F)`、focal + 贪心 guide；
- THRESH：固定窗口的**完全被迫集** `X_H={i: est_i≥a, H-q_i≤b}` 的精确装箱阈值证书；
- 同 `S` 的 `(A,c)` 支配、证明 DAG、`INHERIT`/`DOMINATED-BY` 的局部检查规则。

v0.6 **不推翻** 这些结论，只做四处增量：

1. **Q-STATE / Q-DOM**：状态从 `(S,A,c)` 换成 `(R,A,est)`；支配改用 `A` 与 `est` 的逐分量序。证明模拟引理，并证明它严格包含 v0.5 的 `c` 支配。
2. **TENT-CERT**：把窗口 `[a,b)` 内每个任务的**强制段**
   `e_i=max(0, p_i-(a-est_i)_+-(H-q_i-b)_+)`
   作为 item，做精确装箱；装箱不可行 ⇒ `H` 不可行。固定 `(a,b)` 后 `e_i` 对 `H` 单调不增，故可二分 `H*(a,b)`，一张证书覆盖 `H≤H*`。
3. **TENT-POINT**：在 `H=U-1` 上额外跑一次 TENT 装箱。它与 v0.5 的 AVAIL 高度重叠（30 个实例上只多剪 2 个节点），作为可选层。
4. **EPS-DOM**：`δ`-支配的单次替换引理 `OPT(σ)≤OPT(τ)+δ`，以及预算化 `(1+ε)` 模式的设计。朴素 δ 模式实验无净收益，默认关闭。

关系：

```text
关闭 TENT + Q-DOM                → v0.5 的 (S,A,c) + c-DOM 搜索
只开 Q-DOM                       → 更粗的状态商，仍是精确搜索
只开 TENT（根/周期）              → 更强的状态层下界，仍是精确搜索
全部打开                         → v0.6 完整算法
```

组合下界：

```text
L_X6(σ) = max( L0(σ), L_D(σ), L_AV(σ;U-1), L_TH(σ), L_TENT(σ) )
F(σ)    = 路径上所有 L_X6 的最大值
f(σ)    = max( C(σ), F(σ) )
```

因为同一窗口上 `L_TENT≥L_TH`，且 `F` 取路径最大，所以 `L_X6≥v0.5` 的局部界；关闭 TENT 后 `L_X6=L_X5`，关闭 Q-DOM 后回到 `c` 支配。

## 1. 问题、符号与复用的旧结论

### 1.1 形式化问题

```text
P | prec | Cmax
```

给定任务集 `V={1,...,n}`、工时 `p_i∈Z_{≥1}`、优先约束 `E⊆V×V`（DAG）、
同构机器数 `m`。调度由开始时间 `s_i` 和机器 `μ_i` 组成，满足：

```text
(i,j) ∈ E  ⇒  s_j ≥ s_i + p_i
μ_i = μ_j  ⇒  [s_i, s_i+p_i) 与 [s_j, s_j+p_j) 不重叠
```

目标 `Cmax=max_i(s_i+p_i)` 最小，最优值记 `OPT`。

### 1.2 符号表（v0.6 新增/重定义）

| 符号 | 含义 |
|---|---|
| `R=V\S` | 未调度集 |
| `A=(A_1,...,A_m)` | 排序后的机器可用时间 |
| `c_i` | 已调度任务 `i` 的完成时间（仅用于证明重放） |
| `C(σ)=max_k A_k` | 已提交 makespan |
| `est_i(σ)` | 从 `σ` 出发，任务 `i` 的最早可能开始 |
| `q_i(σ)` | `i` 之后剩余最长路径（不含 `p_i`） |
| `L0(σ)` | `max(C, max_i(est_i+p_i+q_i), ceil(P(R)/m))` |
| `L_D` | v0.5 的时间价格对偶下界 |
| `L_AV(σ;H)` | v0.5 的 AVAIL 窗口装箱下界 |
| `L_TH(σ)` | v0.5 的 THRESH 阈值下界 |
| `L_TENT(σ)` | 本轮强制段装箱阈值下界（§4） |
| `L_X6(σ)` | `max(L0,L_D,L_AV,L_TH,L_TENT)` |
| `F(σ)` | 路径最大下界 |
| `f(σ)` | `max(C(σ),F(σ))` |
| `e_i(a,b;H)` | 任务 `i` 在窗口 `[a,b)` 内的强制处理量（§4.1） |

| `(R,A,est)` | 势商状态（§3） |
| `σ⪯_Q τ` | 势商支配（§3.2） |
| `σ⪯_δ τ` | 加性 δ-支配（§6） |
| `B` | δ-预算 `⌊εL0⌋` |
| `N_max` | 搜索扩展预算 |
| `TENT_ROOT/TENT_SCAN/TENT_POINT` | 三个 TENT 开关 |
| `K_dom` | 每个 `R` 的支配表上限 |
| `B_focal` | 每次 focal 选择最多计算 guide 的候选数 |
| `T_scan` | 根/周期 TENT 扫描间隔 |

### 1.3 复用的 v0.5 结论

以下结论直接继承，不再证明：

- **动作覆盖性**：动作 `(i,k)` 在 `t=max(A_k,est_i)` 开始；从根出发的某条动作序列可达到一个最优调度。
- **CP 初始上界**：按 `q_i` 降序的 CP 表调度给出可行 `U_0`，且 `U_0≤(2-1/m)OPT`（Graham）。
- **前沿下界**：若 `F_open` 覆盖所有可能优于 `U` 的剩余调度，则 `min_{v∈F_open}LB(v)≤OPT`。
- **对偶证书**：`g_H(σ,λ)>0 ⇒ H<OPT(σ)`。
- **AVAIL 可采纳**：若 `BP(X_W,caps(W,σ))` 不可行，则不存在 makespan `≤H` 的完成。
- **证明树**：`TERMINAL/PRUNED/EXACT/EXHAUSTED/PACK-CORE-AVAIL` 的局部检查规则可靠。

v0.6 只替换/扩展状态表示、下界证书和支配；主循环的动作空间与 `L0/L_D/L_AV` 保持不变。

## 2. 动机：三个结构性缺口

### 2.1 缺口一：THRESH 只取帐篷的平顶

v0.5 的 THRESH 对窗口 `[a,b)` 只收集**完全被迫**的任务：

```text
X_H = { i∈R : est_i ≥ a 且 H-q_i ≤ b }
items = { p_i : i∈X_H }
caps_k = max(0, b-max(a,A_k))
```

但任务只要与窗口有交叠，就贡献强制处理量。把 `i` 的最早开始记为 `est_i`、最晚完成记为 `H-q_i`，它在 `[a,b)` 内的强制段是

```text
e_i(a,b;H) = max(0, p_i - max(0,a-est_i) - max(0,H-q_i-b)).
```

作为 `(a,b)` 的函数，这是一个**帐篷**：

- 平顶：`a≤est_i` 且 `b≥H-q_i`，`e_i=p_i`（完全被迫）；
- 斜边：只有一侧被迫，`e_i` 随 `a` 或 `b` 线性下降；
- 外部：`e_i=0`（可以完全放在窗口外）。

v0.5 只取了平顶，把两条斜边丢掉。低截止期、紧窗口时，斜边恰恰是信息量最大的部分。

### 2.2 缺口二：状态商取得太细

v0.5 的状态是 `(S,A,c)`，支配要求 `c` 逐分量更小。但未来只通过“剩余任务的最早开始”与已调度部分发生关系；`c` 的很多差异被更长的剩余路径“吸收”了。把状态压成 `(R,A,est)` 后：

- 转移只依赖 `R,A,est`，不需要 `c`；
- 支配只需 `A` 与 `est` 逐分量比较；
- `c` 支配蕴涵 `est` 支配，所以新支配至少一样强，通常更强。

代价是 `est` 是 `n` 维向量，支配查询仍是高维正交查询；但这是正确的商，也是 TENT 证书的自然接口。

### 2.3 缺口三：“近似”只停留在启发式

v0.5 的 focal/guide 是启发式，没有近似保证。本轮把“近似”拆成两层：

1. **证书的近似**：TENT 用独立 item 的装箱去近似“窗口内精确可行性”。它是单边的：无假阳性，可能有假阴性；近似误差只让下界变弱，答案仍然精确。
2. **支配的近似**：`δ`-支配 + 预算，给出 `(1+ε)` 模式。单次替换有严格引理；不做预算则会累积，最坏情况没有全局保证。默认精确模式。

### 2.4 三个灵感词的分工

- **计算几何**：`(a,b)` 平面上的帐篷函数、临界窗口、强制段装箱；势空间 `(A,est_R)` 的 Pareto 天空线与正交支配查询。
- **确定性算法**：所有窗口、二分、装箱、支配、focal tie-break 都是输入和固定参数的确定函数；不使用 ACO/bandit/MCTS。
- **近似算法**：TENT 是窗口可行性的单边松弛；`δ`-支配是带预算的近似支配，二者都明确区分“近似证书”和“近似答案”。

## 3. 势商：Q-STATE 与 Q-DOM

### 3.1 势商状态

定义状态

```text
σ = (R, A, est)
```

其中 `R⊆V` 是剩余任务，`A∈Z_{\ge0}^m` 是排序后的机器可用时间，`est∈Z_{\ge0}^n` 是剩余任务的最早开始（对 `i∉R` 无意义）。初始状态

```text
σ0 = (V, 0^m, 0^n).
```

转移：选 `i∈R` 且 `pred(i)∩R=∅`，选机器 `k`，令

```text
t = max(A_k, est_i)
A'_k = t + p_i,  其余 A'_j=A_j
A' 重新升序排序
est'_j = max(est_j, t+p_i)   ∀j∈succ(i)∩R
est'_j = est_j               ∀j∈R\{i}, j∉succ(i)
R' = R\{i}
```

终止 `R=∅`，目标值 `max_k A_k`。

**引理 1（势商充分性）**：若两个状态 `σ,τ` 满足 `Rσ=Rτ`、`Aσ=Aτ`、`estσ=estτ`，则从它们出发的可行完成集合与最优值完全相同。

**证明**：对剩余任务数归纳。转移的可用输入只有 `R,A,est`；`c` 只通过 `est` 影响未来（已调度前驱的完成时间已经并入 `est`）。终止目标只读 `A`。因此两个状态的转移系统同构，`OPT` 相同。证毕。

**引理 2（动作覆盖）**：对任意状态 `σ`，若存在一个从 `σ` 出发、makespan `≤H` 的可行完成，则存在一条从 `σ` 出发的动作序列达到它，且每个动作都在当前最早可行时间开始。

**证明**：标准“左移”论证：把每个任务向左移到 `max(A_k,est_i)` 不会增加任何完成时间，也不会破坏优先/机器约束。证毕。

### 3.2 势商支配

对同一个 `R` 下的两个状态 `σ,τ`，定义

```text
σ ⪯_Q τ   iff
    A_σ,k ≤ A_τ,k           ∀k=1..m
且  est_σ,i ≤ est_τ,i       ∀i∈R.
```

**引理 3（模拟）**：若 `σ⪯_Q τ`，则对任意从 `τ` 出发可行的动作序列 `π`，同样的 `π` 从 `σ` 出发也可行，并且在每个前缀后仍满足 `A_σ≤A_τ`、`est_σ≤est_τ`。

**证明**：对 `π` 的长度归纳。初始由 `σ⪯τ`。设当前不变式成立，下一步动作 `(i,k)` 在 `τ` 中可行（`i` 就绪，两边 `R` 相同，所以 `i` 在 `σ` 也就绪）。令

```text
t_σ = max(A_σ,k, est_σ,i) ≤ max(A_τ,k, est_τ,i) = t_τ.
```

新可用时间：`A'_σ,k=t_σ+p_i ≤ t_τ+p_i=A'_τ,k`；其他机器不变。对 `j∈succ(i)∩R`：

```text
est'_σ,j = max(est_σ,j, t_σ+p_i) ≤ max(est_τ,j, t_τ+p_i) = est'_τ,j.
```

其他 `est` 不变。归纳完成。证毕。

**定理 1（支配保序）**：若 `σ⪯_Q τ`，则 `OPT(σ)≤OPT(τ)`。

**证明**：取 `τ` 的最优动作序列，由引理 3 从 `σ` 模拟，最终 `max A_σ≤max A_τ`。证毕。

**推论 1（包含 c-支配）**：若 `A_σ≤A_τ` 且 `c_σ,i≤c_τ,i`（`∀i∈S`），则 `σ⪯_Q τ`。因此 Q-DOM 的前置条件更弱，剪枝至少一样强。

**证明**：对每个 `i∈R`，`est_i` 是若干条形如 `c_j + 路径工时` 的表达式取最大；所有 `c_j` 都不大于 `τ` 的对应值，故 `est_σ,i≤est_τ,i`。证毕。

**严格性例子**：`R={j}`，`Aσ=Aτ=(0,0)`；`σ` 的已调度前驱完成时间为 `(5,3)`，`τ` 为 `(4,4)`。`c` 支配两边都不成立（`5>4`，`3<4`），但 `estσ,j=5`、`estτ,j=4`，所以 `τ⪯_Q σ`，Q-DOM 可以剪掉 `σ`。这个例子说明 Q-DOM 不是 `c` 支配的换皮。

### 3.3 搜索中的支配表

- 对每个 `R` 维护一张 Pareto 表 `D_R`，元素是 `(A,est)`（`est` 只存 `R` 上的坐标）。
- 新状态 `τ` 生成时，若存在 `σ∈D_R` 使 `σ⪯_Q τ`，剪掉 `τ`；若 `τ⪯_Q σ`，从表中删除 `σ`。
- 相同状态（双向支配且 `A,est` 相同）用规范键 `(R,A,est|_R)` 合并，避免 `DOMINATED-BY` 自环。
- 表大小超过 `K_dom` 时停止插入，只做哈希去重；正确性不变，收益下降。

**几何解释**：`(A,est_R)` 是 `R^{m+|R|}` 中的点，`⪯_Q` 是乘积偏序；`D_R` 是下闭集的 Pareto 天空线。支配查询是“是否存在一个点落在查询点的下象限”，即正交支配查询。当前实现是线性扫描 `O(|D_R|(m+|R|))`；更大规模可用 k-d tree / range tree / 分桶网格，但高维下没有银弹。

## 4. TENT-CERT：强制段打包

### 4.1 强制段

固定状态 `σ=(R,A,est)`、候选 makespan `H≥C(σ)`、窗口 `[a,b)`（`0≤a<b≤H`）。对 `i∈R` 定义

```text
e_i(a,b;H) = max(0, p_i - max(0,a-est_i) - max(0,H-q_i-b)).
```

**引理 4（强制段下界）**：在任意从 `σ` 出发、makespan `≤H` 的可行完成中，任务 `i` 在 `[a,b)` 内的处理时间至少为 `e_i`。

**证明**：设 `i` 的开始为 `s_i`、完成为 `c_i=s_i+p_i`。由 `est` 的定义 `s_i≥est_i`；由 `q_i` 的定义 `c_i+q_i≤H`，即 `c_i≤H-q_i`。`i` 在窗口外的部分至多

```text
max(0,a-s_i) + max(0,c_i-b)
≤ max(0,a-est_i) + max(0,H-q_i-b).
```

窗口内的部分为 `p_i` 减去窗口外的部分，再与 0 取 max，故至少为 `e_i`。证毕。

### 4.2 诱导装箱

**引理 5（诱导装箱）**：任意可行完成（makespan `≤H`）诱导一个把 items `{e_i}` 装进 bins `{cap_k}` 的可行装箱，其中 `cap_k=max(0,b-max(a,A_k))`。

**证明**：任务 `i` 在窗口内的段 `J_i=[s_i,c_i)∩[a,b)` 是它所在机器 `μ_i` 上的一段连续区间，长度 `ℓ_i≥e_i`。因为 `s_i≥A_{μ_i}`，`J_i` 落在 `[max(a,A_{μ_i}),b)` 内；同一台机器上的 `J_i` 互不重叠。把每个 `J_i` 缩成大小 `e_i` 的 item，放在原位置，仍然可行。因此 `{e_i}` 可以装进容量为 `cap_k` 的 `m` 个 bin。证毕。

**定理 2（TENT 可靠性）**：若 `BP({e_i},{cap_k})` 不可行（不存在把 items 装入 bins 的分配），则不存在从 `σ` 出发、makespan `≤H` 的完成。

**证明**：反证：若存在完成，由引理 5 诱导一个可行装箱，与 `BP` 不可行矛盾。证毕。

**为什么这是“单边近似”**：`BP` 把强制段当成可以独立放置的 item，忽略了这些段在时间/机器上的更多耦合（例如两条优先链的顺序）。所以它可能漏掉真正的不可行（假阴性）；但只要它报告不可行，就一定不可行（无假阳性）。近似误差只让下界变弱，不会让搜索剪错。

### 4.3 阈值化

**引理 6（对 H 单调）**：固定 `(a,b)`，`e_i(a,b;H)` 对 `H` 单调不增；因此 `BP(items(H),caps)` 的不可行性对 `H` 向下封闭。

**证明**：`H` 减小 ⇒ `H-q_i-b` 减小 ⇒ `max(0,H-q_i-b)` 减小 ⇒ `e_i` 增大。items 逐项变大，装箱只会更难。证毕。

定义

```text
P_σ(a,b) = { H ≥ L0(σ) : BP(items(H),caps) 不可行 }
H*(a,b)  = max P_σ(a,b)        （若 P 为空则不存在）
L_TENT(σ) = max( L0(σ), max_{(a,b)∈Γ(σ,U)} (H*(a,b)+1) ).
```

**定理 3（阈值可采纳）**：若 `H*(a,b)` 存在，则 `OPT(σ) ≥ H*(a,b)+1`；因此 `L_TENT(σ)≤OPT(σ)`。

**证明**：`H*` 处 `BP` 不可行，由定理 2，不存在 makespan `≤H*` 的完成；整数时间 ⇒ `OPT≥H*+1`。对窗口取 max、与 `L0` 取 max 仍不超过 `OPT`。证毕。

**定理 4（包含 THRESH）**：固定同一个窗口 `(a,b)` 和 `H`，若 v0.5 的 THRESH 判定 `H` 不可行，则 TENT 也判定 `H` 不可行。因此 `L_TENT≥L_TH`（在相同窗口族上）。

**证明**：对 `i∈X_H`（`est_i≥a` 且 `H-q_i≤b`），两个 max 项都为 0，故 `e_i=p_i`；对 `i∉X_H`，`e_i≥0`。所以 TENT 的 item 多重集包含 THRESH 的全部 item，外加一些非负 item。若 THRESH 的 item 已经装不下，加入更多 item 只会更难装下。证毕。

**真实的状态级严格例子（`pool30[0]` 的一个前缀）**：

```text
S={0,1,4}, A=(0,10), c=(4,6,-1,-1,10,-1,-1,-1,-1)
est=(4,6,0,0,10,3,0,4,10), q=(0,0,0,4,0,3,3,0,0)
L0=13, U=16, OPT=15（独立 DFS）
窗口 [0,13), H*=14, caps=(13,3)
TENT items=(4,3,1,5,2,2)，总和 17>16 -> BP 不可行，TENT=15
THRESH 在同一窗口 H=14 只看到 X={3,5,6}（est≥0 且 14-q≤13），
items=(3,1,5)，可装为 3 | 1+5 -> 不报警，THRESH=14
```

`THRESH` 的全局阈值是 14（`H=14` 时没有任何窗口报警）；TENT 的 15 正好等于 OPT。差别来自 TENT 把部分任务的强制段（4,2,2）也作为 item，使总和超过 `caps` 的 16。

### 4.4 窗口族与算法

**窗口族**：对状态 `σ` 和当前上界 `U`，取

```text
A_vals = {0} ∪ {est_i} ∪ {est_i+p_i} ∪ {A_k}
B_vals = {U-1} ∪ {U-1-q_i} ∪ {U-1-q_i-p_i} ∪ {est_i+p_i} ∪ {A_k}
Γ(σ,U) = { (a,b) : a∈A_vals, b∈B_vals, 0≤a<b≤U-1 }.
```

它包含 v0.5 的 `make_windows` 族（`a∈{0,est_i}`，`b∈{max A, est_i+p_i, (U-1)-q_i}`）。任何子集都是可靠的；更大的族只会更强，不会更弱。当前实现用这个 `O(n^2)` 的离散族；完整的 `(a,b)` 平面扫描/上包络是下一轮的优化。

**TENT-THRESH(σ,U)**：

```text
1  est,q ← HEADS-TAILS(σ)                 # 从 R,A,est 重算
2  Γ ← WINDOW-FAMILY(σ,U)
3  best ← L0(σ)-1
4  for (a,b) ∈ Γ:
5      lo ← L0(σ);  hi ← U-1
6      while lo ≤ hi:
7          mid ← floor((lo+hi)/2)
8          if PACK-TENT(σ,mid,a,b):     # BP(items,caps) 不可行
9              best ← max(best,mid);  lo ← mid+1
10         else: hi ← mid-1
11 return max(L0(σ), best+1)
```

**PACK-TENT(σ,H,a,b)**：

```text
1  caps_k ← max(0, b-max(a,A_k))          # k=1..m
2  items ← []
3  for i∈R:
4      u ← max(0, a-est_i)
5      v ← max(0, H-q_i-b)
6      e ← p_i-u-v
7      if e>0: items.append(e)
8  if items=∅: return False
9  return not BP(items,caps)              # True = 证明不可行
```

**BP**：

- `m=1`：`sum(items) ≤ caps_1`。
- `m=2`：精确 bitset 子集和；`bits=1; for s in items: bits|=bits<<s`；存在子集和落在 `[max(0,total-c_2),c_1]` 即可行。
- `m≥3`：完整的 `PACK-BB`（按 item 降序的分支限界），或退化的总能量测试 `sum(items)≤sum(caps)`（可靠但弱）。本轮 m=2 用精确 bitset；m>2 未实现精确版。

**TENT-POINT(σ,U)**：只检查 `H=U-1`，窗口族同上；若任一窗口 `PACK-TENT` 为真，则 `U` 不可行，节点可剪。它是 TENT-THRESH 的特例，成本低但收益也小（实验：139→137）。

### 4.5 成本

设 `W=|Γ|=O(n^2)`，`T_BP` 是一次装箱测试的成本。则一次 TENT-THRESH 为

```text
O( W · log(U-L0) · T_BP ).
```

`m=2` 的 bitset 为 `O(|R|·S_total/word)`，`S_total=Σ p_i`；`m>2` 的 `PACK-BB` 最坏指数于 `m`，但 `m` 小。当前实现只在根节点/每 `T_scan` 次扩展运行 TENT-THRESH；每个子节点只跑 v0.5 的 AVAIL 点测试（可选再加 TENT-POINT）。

## 5. 主循环 X-DUB/TQ*

### 5.1 节点与不变量

每个搜索节点存：

```text
v = (R, A, est, F, f, parent, action, id)
```

其中 `F` 是从根到 `v` 的路径上所有 `L_X6` 的最大值，`f=max(max(A),F)`。不变量：

```text
F(v) ≤ OPT(v) ≤ U,        f(v) ≤ OPT(v),
f(child) ≥ f(parent),     F(child) ≥ F(parent).
```

（`OPT(v)` 是从 `v` 出发的绝对 makespan 最优值；`U` 是当前可行上界。）

### 5.2 伪代码

```text
算法 X-DUB/TQ*(G,p,m,N_max)
────────────────────────────────────────────────
1  (L0,q) ← PRECOMPUTE(G,p,m)
2  π0,U0 ← MIN-GREEDY(G,p,m)          # CP/LPT/MWKR 三条表调度取 min
3  best ← (U0,π0);  U ← U0
4  root ← NEW-NODE(R=V, A=0^m, est=0^n)
5  root.L ← L0(root)
6  if TENT_ROOT:
7      root.L ← max(root.L, TENT-THRESH(root,U))
8  root.F ← root.L;  root.f ← max(0,root.F)
9  Open ← {root};  Dom ← {V: [(0^m,0^n)]}
10 Lglob ← root.L;  t ← 0
11 while Open ≠ ∅ and t < N_max:
12     purge Open 中 f≥U 的节点
13     if Open=∅: break
14     f_min ← min_{v∈Open} f(v)
15     if f_min ≥ U: break
16     if FOCAL:
17         Φ ← {v∈Open : f(v) ≤ f_min+ω}
18         v ← argmin_{v∈Φ, |Φ|≤B_focal} (GUIDE(v), f(v), KEY(v))
19     else:
20         v ← argmin_{v∈Open} (f(v), KEY(v))
21     t ← t+1
22     U ← min(U, GUIDE(v))              # 贪心完成，可行上界
23     for each child w=(R',A',est') of v:
24         if R'=∅:
25             U ← min(U, max(A'));  continue
26         l0 ← L0(w)
27         if l0 ≥ U: continue
28         if AVAIL(w,U-1): continue      # v0.5 点测试
29         if TENT_POINT and PACK-TENT-ANY(w,U-1): continue
30         g ← GUIDE(w);  U ← min(U,g)
31         F_w ← max(v.F, l0)
32         f_w ← max(max(A'),F_w)
33         if f_w ≥ U: continue
34         if Q-DOMINATED(w,Dom[R']): 
35             record DOMINATED-BY;  continue
36         insert w into Open;  update Dom[R']
37     if TENT_SCAN and t mod T_scan = 0:
38         Lnew ← TENT-THRESH(root,U)
39         Lglob ← max(Lglob,Lnew)
40         for x∈Open:
41             x.F ← max(x.F,Lglob);  x.f ← max(max(A_x),x.F)
42         purge Open 中 f≥U
43 L ← max(Lglob, min_{v∈Open} f(v) default Lglob, L0(root))
44 if Open=∅ or L≥U:
45     PROOF ← BUILD-PROOF-DAG(root,U)
46 return best,L,U,gap=(U-L)/max(1,L),PROOF
```

**确定性 tie-break**：`KEY(v)=(R, A, est|_R, parent.id)` 是规范键；`GUIDE` 用三条贪心规则 `CP/LPT/MWKR`，规则内部用 `(-q_i, -p_i, i)` / `(-p_i,i)` / `(-remaining_work_i,-p_i,i)` 的固定次序；focal 的 `Φ` 按 `(f, KEY)` 排序。没有随机数、没有学习、没有哈希顺序依赖。

**商上的旧算子**：`L0/L_AV/THRESH/GUIDE` 都可以在 `(R,A,est)` 上计算：`est` 已经包含已调度前驱的完成时间，`q` 由 `R` 和原 DAG 重算；不需要 `c`。

**与 v0.5 的差异**：

- 状态从 `(S,A,c)` 换成 `(R,A,est)`；转移与支配相应改变。
- 根/周期多了一个 `TENT-THRESH`；子节点可选 `TENT-POINT`。
- `GUIDE`、focal、`INHERIT`、AVAIL 点测试保持不变。
- 关闭 `TENT_*` 和 `Q-DOM`，用 `c` 支配，即回到 v0.5 的搜索语义（除状态实现细节外）。

### 5.3 根/周期 TENT 的作用

- **根节点**：`Lglob` 一次性抬高，所有节点继承；这是本轮节点数下降的主要来源（195→139）。
- **周期扫描**：每 `T_scan` 次扩展，用当前 `U` 重算根证书；`U` 下降后窗口族变小，但旧证书仍有效，所以 `Lglob` 只增不减。
- **内部节点**：默认不跑 TENT-THRESH，只跑便宜的 AVAIL；可选 TENT-POINT 在 `H=U-1` 上补一刀。实验显示 TENT-POINT 只多剪 2/139 个节点，故默认关闭，留给“容量紧、AVAIL 刚好漏掉”的实例。

## 6. 近似层：δ-支配与预算

### 6.1 单次替换引理

对同一个 `R`，定义加性 δ-支配：

```text
σ ⪯_δ τ   iff
    A_σ,k ≤ A_τ,k + δ          ∀k
且  est_σ,i ≤ est_τ,i + δ      ∀i∈R.
```

**引理 7（δ-模拟）**：若 `σ⪯_δ τ`，则 `OPT(σ) ≤ OPT(τ)+δ`。

**证明**：取 `τ` 的最优完成调度，开始时间为 `s_i`。把每个开始时间右移 δ：`s'_i=s_i+δ`。

- 机器可用：`s'_i≥A_τ,μ(i)+δ≥A_σ,μ(i)`；
- 优先约束：`s'_j-s'_i=s_j-s_i≥p_i`，间距不变；
- 机器不重叠：同一机器上的间距不变；
- 最早开始：`s'_i≥est_τ,i+δ≥est_σ,i`。

所以右移后的调度从 `σ` 可行，makespan 为 `OPT(τ)+δ`。证毕。

**推论 2**：若搜索在节点 `τ` 上用 `σ` 做 δ-支配剪枝，则 `σ` 的最优完成最多比 `τ` 差 δ；单次替换不会把答案推高超过 δ。

### 6.2 朴素模式（实验用）

固定 `δ`（例如 1），不做预算：

```text
若存在 σ∈Dom[R] 使 σ⪯_δ τ，则剪掉 τ。
```

实验（30 个困难实例，精确模式 139 次扩展）：

```text
δ=1：141 次扩展；k=27 从 25 降到 20，k=29 从 30 升到 37；其余 28 个不变。
```

**结论**：δ=1 在这批实例上没有净收益，且会因改变 focal 顺序而伤害个别实例；它不是一个免费的加速器。默认精确模式（δ=0）。

### 6.3 预算化 (1+ε) 模式（设计，未实现）

把预算 `b` 并入状态：`(R,A,est,b)`。根预算 `B=⌊εL0⌋`。当 `τ=(R,Aτ,estτ,bτ)` 被 `σ=(R,Aσ,estσ,bσ)` δ-支配时：

1. 要求 `bσ≥δ`；
2. 不直接复用 `σ` 的旧搜索，而是把 `σ` 以预算 `bσ-δ` 重新入队（若 `(σ,bσ-δ)` 未出现过）；
3. 沿任一条替代链，预算严格减少 δ，故总误差 ≤B。

**定理 5（预算化近似）**：若预算化搜索正常终止（`Open=∅` 或 `L≥U`），则

```text
OPT ≤ U ≤ OPT + B ≤ (1+ε)OPT.
```

**证明要点**：沿一条从根到最优完成的最优动作路径。每当路径上的节点被 δ-支配剪掉，就切换到支配者，并由引理 7 把剩余最优完成右移 δ；预算减少 δ。总替换次数 ≤B/δ，累计误差 ≤B。搜索的完备性保证最终到达一个完整状态，其 makespan ≤OPT+B。`U` 可行，故 `OPT≤U`。证毕。

**代价**：同一个 `(R,A,est)` 可能以不同预算被多次展开；这是 `(1+ε)` 保证的代价。朴素模式省掉了这个代价，但也省掉了保证。

## 7. 证明 DAG 与 checker

### 7.1 节点类型

在 v0.5 的 `TERMINAL/PRUNED-DUAL/PACK-CORE-AVAIL/EXACT/EXHAUSTED` 上新增：

```text
TENT-CORE(R,A,est, a, b, H*, items, caps, path)
INHERIT(parent)
DOMINATED-BY(σ)
```

- `TENT-CORE`：固定窗口的强制段装箱证书；`path` 是从根到该状态的动作序列（checker 用来独立重算 `c/est`）。
- `INHERIT`：子节点的 `F` 不小于父节点；父证书有效。
- `DOMINATED-BY`：被支配状态的见证；支配者必须在 DAG 中有已检查的证明或已闭合的子树。

### 7.2 checker 规则

```text
CHECK-NODE(v):
1  if v in memo: return memo[v]
2  if v in stack: reject                  # 环
3  case v.type:
4    TERMINAL:
5        按 path 重放动作；所有任务恰好一次；前驱/机器约束成立；
6        验证 max(A) = C(v)；若 C(v) < U，作为 incumbent 验证；否则作为闭合验证
7    PRUNED-DUAL:
8        验证 v 的对偶证书 g_H(σ,λ)>0
9    PACK-CORE-AVAIL:
10       按 v0.5 规则验证 (H,a,b,X,π)
11   TENT-CORE:
12       按 path 独立重算 c, est, q（不信任搜索器缓存）
13       验证 0≤a<b；验证 H* ≥ L0(σ)
14       items ← []
15       for i∈R:
16           e_i ← max(0, p_i - max(0,a-est_i) - max(0,H*-q_i-b))
17           if e_i>0: items.append(e_i)       # 直接重算，忽略声称值
18       caps_k ← max(0, b - max(a,A_k))
19       验证 BP(items,caps) 不可行（m=2 用独立 bitset；m>2 用 PACK-BB）
20       # 由引理 6，所有 H≤H* 自动不可行；无需枚举
21       若该节点用于剪枝，验证 H*+1 ≥ 阈值（U 或组合后的 f）
22   INHERIT(parent):
23       验证 F(v) ≥ F(parent)；return CHECK-NODE(parent)
24   DOMINATED-BY(σ):
25       验证 R_v=R_σ
26       按各自的 path 重算 est；验证 A_σ,k ≤ A_v,k (∀k) 且 est_σ,i ≤ est_v,i (∀i∈R)
27       验证 CHECK-NODE(σ)
28       验证 (LB(σ)≥U) 或 (σ 的子树已闭合)
29   EXACT/EXHAUSTED:
30       按 v0.5 规则递归检查所有动作/子节点
31   else: reject
32  memo[v] ← true; return true
```

**DAG 条件**：`DOMINATED-BY` 和 `INHERIT` 可能产生共享子证明；checker 用 `memo` 复用，用 `stack` 拒绝环。δ=0 的 `⪯_Q` 是偏序；相同状态的 transposition 在构造时合并成一个节点，不产生自环。

### 7.3 可靠性

**定理 6（证明 DAG 可靠）**：若 `CHECK(root)` 通过，且 incumbent 路径可行并返回 `U`，则 `U=OPT`。

**证明**：对 DAG 做拓扑归纳。

- `TERMINAL`：路径可行，故 `OPT≤C`；若 `C≥U`，该分支没有更好的完成。
- `PRUNED-DUAL`/`PACK-CORE-AVAIL`：v0.5 的可靠性。
- `TENT-CORE`：定理 2/3；`H*` 处不可行，且 `H*+1` 达到剪枝阈值，故该分支没有 `<U` 的完成。
- `INHERIT`：`F` 是绝对下界，父下界对子有效；数值不小于父，故仍有效。
- `DOMINATED-BY`：引理 3/定理 1；支配者的 `OPT` 不大于被支配者；若支配者已闭合或 `LB≥U`，被支配者也没有 `<U` 的完成。
- `EXACT/EXHAUSTED`：所有动作/子节点覆盖，归纳假设给出每个子节点没有更好的完成。

结合 incumbent 可行（`OPT≤U`）与根闭合（`OPT≥U`），得 `U=OPT`。证毕。

### 7.4 独立性

- `est/q/A` 由 checker 从 `path` 和原 DAG 重算，不信任搜索器缓存；
- `items` 和 `caps` 由 checker 重算，不信任声称值；
- `BP` 不可行性由 checker 用独立的精确算法验证；
- `H*` 的二分、窗口族、focal、guide、δ 都不在证明 DAG 里；
- `TENT-CORE` 的区间性质由引理 6 保证，不需要为每个 `H` 附一份子集和证据；
- `DOMINATED-BY` 的见证状态必须在 DAG 中有已检查的证明。

### 定理 7（任意时刻区间）

```text
L ≤ OPT ≤ U.
```

### 定理 8（终止即最优）

若算法因 `Open=∅` 或 `L≥U` 终止，则 `U=OPT`。

**证明**：若存在 `Cmax<U` 的完成，由动作覆盖性和前沿覆盖性，它必须经过某个开节点 `v`，且 `f(v)≤Cmax<U`。这与 `Open=∅` 或 `min_{v∈Open}f(v)≥U` 矛盾。结合 `U` 可行，得 `U=OPT`。证毕。

### 定理 9（有限完备性）

搜索树有限；每次展开前进一个任务；Q-DOM 只删除被支配的状态（由定理 1 不丢更优完成）；TENT 只删除没有 `<U` 完成的分支（由定理 2/3）；focal 可能延迟但不会无限跳过可展开节点。预算无限时前沿最终为空或 `f_min≥U`。最坏时间复杂度仍指数；这是 NP-hard 问题的预期行为。

## 9. 复杂度分析

### 9.1 单次操作

- **预处理**：拓扑排序 + head/tail，`O(n+|E|)`。
- **L0**：`O(n+|E|)`。
- **AVAIL 点测试**：`O(n^3)` 朴素（窗口族 `O(n^2)` × 强制集 `O(n)`），可用排序/前缀降到 `O(n^2)`；记 `T_AVAIL`。
- **m=2 精确装箱**：bitset `O(|X|·S_total/word)`；小核可用 MITM。
- **TENT-THRESH**：`O(|Γ| log(U-L0) T_BP)`，`|Γ|=O(n^2)`；只在根/周期启用。
- **TENT-POINT**：`O(|Γ| T_BP)`；可选。
- **贪心组合**：每条约 `O(n(n+|E|))`；三条规则为常数因子；可增量化为 `O(n log n+|E|)`，本轮未做。
- **focal 选择**：扫描 `Open` 为 `O(|Open|)`；guide 计算最多 `B_focal` 次，`O(B_focal·T_G)`。
- **Q-DOM**：每个 `R` 的 Pareto 表大小 `|D_R|`；单次 `O(|D_R|(m+|R|))`，受 `K_dom` 限制。
- **证明 DAG 检查**：`O(N_proof+|E_proof|)`。

### 9.2 总复杂度

设 `N` 为物化节点数、`N_max` 为扩展预算：

```text
时间: O( N·(T_AVAIL + T_G) + N_max·T_G·B_focal
        + N·K_dom·(m+n) + T_TENT(root) + T_TENT(scan)·(N_max/T_scan) )
空间: O( N(n+m) + Σ_R |D_R|(n+m) + N_proof )
```

最坏情况：

```text
N = O((m·n)^n)
T_AVAIL = O(n^2 + |X|·S_total/word)
T_TENT = O(n^2 log U · T_BP)
```

- v0.6 没有改变最坏复杂度；它是“更强的证书 + 更粗的状态商 + 更少的重复状态”，不是新的多项式算法。
- `T_G` 与 `B_focal` 是主要常数开销；n≤15 时可接受，n 很大时需要增量贪心和 guide 缓存。
- `K_dom` 控制支配表内存；超过上限后退化为哈希去重，正确性不变。
- TENT 是根/周期操作；若每节点都跑 TENT-THRESH，成本会变成 `O(N n^2 log U T_BP)`，在 n≥30 时可能压过节点收益。这是本轮把 TENT 限制在根/周期的原因。

### 9.3 成本控制

- TENT-THRESH 只在根/每 `T_scan` 次扩展运行；
- 子节点只跑 AVAIL 点测试；TENT-POINT 默认关闭；
- Q-DOM 表按 `R` 分桶，超过 `K_dom` 停止插入；
- 证明 DAG 只在终止时构造，checker 与搜索器隔离；
- 窗口族用 `O(n^2)` 离散临界值，不做完整平面扫描。

### 10.5 状态级阈值对比

在 30 个实例上随机取 78 个可达前缀状态（随机 25%/40%/55% 调度），比较 v0.5 THRESH 与 TENT：

| 指标 | `L0` | THRESH | TENT |
|---|---:|---:|---:|
| 总和 | 1685 | 1872 | **1912** |
| 均值 | 21.60 | 24.00 | **24.51** |
| TENT ≥ THRESH | — | — | **78/78** |
| TENT 严格更好 | — | — | **30/78** |
| TENT 更差 | — | — | **0/78** |
| 装箱测试 | — | 3149 | 10291 |

这说明 TENT 不是只在根节点有用；在任意状态上，它都不弱于 THRESH，且在 38% 的采样状态上严格更强。

### 10.6 可靠性验证

- **118 个 TENT 声明，0 个假阳性**：在 40 个 n=7–8 的随机实例上，对随机前缀状态和 `H∈[L0,OPT-1]` 采样；每个 TENT 报告“不可行”的 `(σ,H)`，都用独立的有界 DFS（从 `σ` 出发、截止 `H`）确认不存在完成。
- **40/40 根 TENT ≥ THRESH**：同一批随机实例上，TENT 的根下界从不低于 THRESH。
- **60 个新鲜 n=9 实例**：57 个 `L0=OPT`；只有 3 个有 gap；TENT 总和比 THRESH 多 1（8 vs 7），1/60 严格更好，0/60 更差，最大 `TENT-OPT=0`。
- **m=2 的装箱是精确的**：bitset 子集和；没有用总能量近似。

### 10.7 负结果与消融

**（a）窗口族消融**：TENT 用 v0.5 旧窗口族，根下界总和 695；用完整 `(a,b)` 族，697。完整族只在 k=27、k=29 上各加 1。  
**结论**：主要收益来自“部分 item”，不是“更多窗口”；二维窗口扫描是二阶改进。

**（b）链容量证书**：对每条优先链，检查 `Σ e_i ≤ b-a`（链上的强制段必须顺序执行）。在 78 个随机状态上：

```text
chain > PACK：0/78
chain < PACK：62/78
chain = L0：78/78
```

**结论**：链容量被 `L0` 的最长链下界支配；简单的“链在窗口内装不下”不是 precedence gap 的正确松弛。这个负结果说明 k=29 的 1 个单位需要更强的顺序/机器耦合证书，而不是再加一个链和。

**（c）δ-支配**：δ=1 总扩展 141，精确 139；k=27 从 25 降到 20，k=29 从 30 升到 37。  
**结论**：近似支配不是当前瓶颈；默认 δ=0。

**（d）周期 TENT**：在 n≤10 的 30 个实例上，节点数都 <40，`T_scan=40` 从未触发。它在本轮没有数据；留给 n≥20 的规模实验。

### 10.8 规模与成本

- 根 TENT 在 n=12–30 的随机实例上：窗口数 121–768，单实例 ≤0.006 秒；在这些“L0 已紧”的实例上，TENT 与 THRESH 相同，没有额外收益。
- TENT 的成本随 `|Γ|=O(n^2)` 和 `log(U-L0)` 增长；m=2 的 bitset 很便宜，m>2 的精确 PACK-BB 是下一轮的瓶颈。
- 本轮没有 n≥20 的 anytime 曲线；不能外推。

### 10.9 Anytime（困难 7 实例）

平均剩余 gap（`U_best-OPT`，在预算处截取）：

| 预算 | `L0` + AVAIL | 根 TENT |
|---:|---:|---:|
| 5 | 0.571 | **0.429** |
| 10 | 0.286 | 0.286 |
| 20 | 0.143 | 0.143 |
| 40 | 0.000 | 0.000 |

TENT 只在最早期（5 次扩展）略好；40 次后两者都找到 OPT。本轮的主要收益是**更少的证明节点**，不是 anytime 曲线。

### 10.10 解读

1. **根证书是杠杆**：30 个实例上只多 6 个单位的根下界，却省了 28.7% 的扩展；因为多出来的 1–2 个单位正好落在最难的实例的根上。
2. **部分 item 是核心**：旧窗口族已经能拿到 695/697 的收益；二维窗口扫描只加 2 个实例。
3. **Q-DOM 理论强、数据弱**：它严格包含 `c` 支配，但在 AVAIL 之后只多剪 2.5%；它更适合作为状态表示和 TENT 的接口，而不是主卖点。
4. **近似支配不是瓶颈**：δ=1 无净收益；真正需要近似的是“窗口可行性”，而 TENT 已经用单边松弛做了。
5. **顺序 gap 仍在**：k=29 的 `L_TENT=34`、`OPT=35`；链容量、装箱、能量都关不上。这是下一轮要攻的方向。

## 11. 已知风险

1. **TENT 是单边松弛，会漏**：它只检测“强制段装不下”的不可行；对顺序/机器耦合导致的不可行（k=29）无能为力。不要把它宣传成完整窗口可行性测试。

2. **收益集中在困难尾部**：60 个新鲜 n=9 实例中只有 3 个 `L0<OPT`；TENT 在 1/60 上严格更好。平均随机实例的收益接近于零；30 个困难实例的结果有选择偏差。

3. **窗口族是启发式的**：`Γ` 只取 `O(n^2)` 个临界值；完整的 `(a,b)` 平面扫描/上包络没有实现。更大的族只会更强，但成本也更高；当前族可能漏掉更强的窗口。

4. **m>2 的装箱未实现**：m=2 用精确 bitset；m>2 目前只有总能量测试（可靠但弱）。要发挥 TENT 的全部威力，需要 `PACK-BB` 和它的独立 checker。

5. **Q-DOM 的表可能爆炸**：`(A,est_R)` 的维度是 `m+|R|`；Pareto 前沿在最坏情况下指数大。`K_dom` 截断后只保留部分支配，正确性不变但收益下降；高维正交查询没有银弹。

6. **Q-DOM 只对同一个 `R` 有效**：不同已调度集之间没有本轮的支配关系；不能把“少调度一个任务”的状态直接与“多调度一个任务”的状态比较。

7. **根下界改变 focal 顺序**：更高的 `F` 会改变 `f` 的分布和 focal 候选集，guide 的 tie-break 可能改变搜索路径；原则上可能出现“下界更高但节点更多”的实例（δ=1 的 k=29 就是一个信号）。本轮 30 个实例上没有出现 Q+TENT 对 Q 的节点回退，但不能保证。

8. **δ-模式的全局保证未实现**：朴素 δ 模式没有 `(1+ε)` 保证；预算化模式需要把 `b` 并入状态并可能重复展开支配者，本轮只有设计。默认必须用 δ=0。

9. **证明 DAG 未实现**：118/118 的验证是“TENT 声明 vs 独立 DFS”，不是完整的 proof-DAG checker。`TENT-CORE`、`DOMINATED-BY`、`INHERIT` 的 checker 还没有对拍；一个错误的 `est` 重放或支配方向会接受假最优。

10. **势商假设同构机器、无 release date、非抢占**：`A` 排序后的逐分量比较只在同构机器上成立；unrelated machines、机器 release time、抢占/迁移都会破坏模拟引理。不要直接套用。

11. **TENT 依赖 `est/q` 的正确性**：如果 `est` 或 `q` 缓存有 bug，强制段会算错，证书可能不可靠。checker 必须从 `path` 和原 DAG 独立重算。

12. **整数时间与 bitset 规模**：m=2 的 bitset 大小是 `S_total=Σp_i`；`p_i` 很大时内存/时间会爆炸。需要用 MITM 或 B&B 替代；当前只适合小 `S_total`。

13. **实验规模小**：n=9–10、m=2、30 个筛选实例；没有 PSPLIB、没有 n≥20 的 anytime、没有 m>2。时间数据是纯 Python 单次测量，不是 benchmark。

14. **TENT 与 THRESH 的包含关系依赖同一窗口/同一 caps**：如果 TENT 和 THRESH 用了不同的 `(a,b)` 或不同的容量定义，“TENT≥THRESH”的声明要重新核对。`b>H` 时 caps 偏大、测试更弱，但可靠性不受影响。

15. **根证书的 `U` 依赖**：窗口族用 `U-1` 生成；`U` 很松时族更大、成本更高；`U` 很紧时族更小。`Lglob` 只增不减，旧证书仍有效，但新扫描可能不再产生新界。

---

## 12. 一句话最大风险

**TENT 的收益集中在根节点、低截止期、容量–截止期耦合的困难尾部；在 precedence-heavy 或 m>2 的大实例上，窗口枚举与精确装箱的成本可能超过它省下的节点，而它对纯顺序 gap（k=29 的 L=34 vs OPT=35）仍然无能为力。**
