# 研究循环 · 本轮灵感：「动作分块」×「电池管理」 → MetricVoiceGauge-NCD-HUTDH-v23

> **基线**：承接 v22（MetricVoiceGauge-NCD-HUTDH-v22：PGEV 三层能量可行性 + HDL/DCL 义务合规 + ACSC 机械臂配空间 + DCSC conformal 深度感知 + HPC-E 统一准入门 + CFC++ 层级模态共识；其上承 v21 的 SDC/CAC/DCL/GIC 语义-规范层与 v20 联邦感知证书 PCA/CTS/CFC/HPC、v19 DCM/OGCC/CCV/DRS/OGC、v17 CLP/S2C/HCG/PSV/APS/AMC）。
> 本轮纪律：**动作是"能被证明向前承诺多久"的时序单元；电池是"带估计不确定与退化的功率-能量双预算"**。不推倒 v22：PGEV/EVC/HDL/ACSC/DCSC/HPC-E/CFC++ 全部保留。本轮只做一件事：在 v22 的"逐时刻可行"之上加一层"**分块承诺 + 功率约束储备**"的时序-储能证书层，把"此刻可行"升级为"这段时间敢承诺"，并顺手封堵 v22 的活性坍缩与"能量-功率混淆"风险。

## 0. 直觉与动机

**灵感 1（动作分块 → 安全验证的天然时间粒度是"块"，但可承诺的长度必须被证书裁短）**
直觉：现代操作/导航策略（ACT、Diffusion-Policy 类）不再逐帧吐动作，而是一次输出一段"动作块" `A=(a_t,…,a_{t+H-1})`，执行前 k 步再重规划（receding horizon）。这带来一个被忽视的安全红利与一个被忽视的安全债务。**红利**：验证成本可按块摊销——一次可达管道（reachable tube）过近似即可覆盖整段。**债务**：块与块之间有接缝；块的后半段是在"旧观测 + 旧能量估计"上做出的盲目承诺；块内安全既不等于拼接后安全，也不等于承诺期间观测/电量仍有效。核心洞察：**块长 H 不该由平滑度或策略先验决定，而应由证书决定**——真正能提交执行的只是"认证前缀" `L* = min(L_safe, L_obs, L_energy, L_stitch, L_therm)`。把"想多远"(H) 与"敢承诺多远"(L*) 解耦，是本轮最干净的一刀：可以长块推理，但必须短前缀承诺。副产品：相邻两次预测的重叠段若不一致，正是模型/感知漂移的免费探针（时序一致性监控）。

**灵感 2（电池管理 → 储备不是"焦耳账户"，而是"功率可行的生存核"，且随老化/温度收缩）**
直觉：v22 的 EVC 把安全回退写成能量不等式 `E_res ≥ E_fallback + E_reach_safe + E_margin`。电池管理给出两条更狠的事实。第一，**能量够 ≠ 功率够**：接近空电时开路电压 `V_oc` 塌陷、内阻 `R_int` 上升，峰值放电功率 `P_avail_max(SoC,T,SoH)` 会先于总能量枯竭而失效——机器人"账上还有电"，却已给不出刹车/转向所需瞬时功率；更隐蔽的是高 SoC 侧**回馈制动受电功率上限** `P_accept_max`：充满电时反而刹不住，制动距离变长。第二，**所有电池量都是估计量**：只能给置信区间 `[SoC^lo, SoC^hi]`、`SoH^lo`，证书必须用保守下界，并随老化、温度事件、换电重签。核心洞察：**真正决定能否安全停下的不是剩余能量，而是回退机动全程的功率可行性**——`K_energy` 必须升级为功率可行的生存核 `K_pow`。这与灵感 1 精确耦合：承诺前缀越长，回退窗口越长，对功率持续性的要求越高。

**两者如何统一：承诺长度 = 各有效期的最小值**
把动作块看作"一次证书签发"，把电池看作"证书的预算与期限"，统一成一个**时序-储能证书层**：
- **ACC**（动作分块证书）回答"这一块按可达管道是否安全，且我最多敢执行前多少步"；
- **BSC**（电池状态证书）回答"在这段承诺窗口内，保守 SoC/SoH 下的功率与能量双预算是否始终支撑回退"；
- **CRLC**（充电会合活性证书）回答"若本地回退功率不可行，能否经认证会合到充电/安全态"——这是活性出口，专治 v22 的活性坍缩。
统一准入门升级为 **HPC-EC = (HPC-E, ACC, BSC, CRLC)**：几何∧规范∧负信息∧能量可持续∧差距内未证伪（v22 原样保留）∧ **分块可承诺 ∧ 功率可行储备 ∧ 会合可达**。共享状态 `ζ_pgev` 扩为 `ζ_tempo = ζ_pgev ∪ (A_t, R_t(A), L*, SoC^lo/hi, SoH^lo, P_avail_max, P_accept_max, bsc_id, crl_id)`。安全继承：ACC 只裁短提交前缀、BSC 只收紧预算、CRLC 只提供回退目标，故 `Exec_v23 ⊆ Exec_v22` 由构造保持。

## 1. 研究问题（轮次升级版）

- **Q1（分块可证与接缝归纳）**：如何由动作块 `A` 与有界扰动集 `W` 导出可靠可达管道 `R_t(A)`，使 `R_t(A) ⊇ 真实可达集` 以 ≥1-δ 成立？相邻块的"交接不变量"如何定义，才能让"每段认证前缀结束于交接安全集"归纳出整条轨迹安全，而不在接缝处出现安全缝隙？

- **Q2（功率-能量双预算）**：如何由等效电路模型 `(V_oc(SoC), R_int(SoC,T,SoH))`、保守界 `SoC^lo/SoH^lo/T^hi` 导出全程 `P_avail_max` / `P_accept_max`，并把 `E_res ≥ Σ` 的能量不变量升级为"能量足 ∧ 全程功率可行 ∧ 热可行"的生存核 `K_pow`？回退机动本身的功率需求如何上界化（制动/转向/让位）？

- **Q3（承诺前缀最优化与活性）**：`L* = min(…5 项)` 的每一项如何在线 O(1) 计算与更新？块长 H 与承诺长度 L* 的最优配比（推理摊销收益 vs 盲承诺代价 vs 功率预留）如何求解？CRLC 的"会合可达"判定与 `L_stitch` 如何避免在"功率将将够/将将不够"之间振荡？

- **Q4（退化与重签的审计）**：SoH 估计更新、换电、热事件、低温标定漂移如何触发 BSC 失效与重签？每张 BSC/ACC 如何锚定电池 ID、单体电压哈希、BMS 固件版本、标定数据哈希，防止"健康电池签发的证书被静默复用到退化/换过的电池"？退化下"证书只在原 SOH 有效"的单调性如何形式化？

## 2. 设计原则（在 v22 的 P34–P42 基础上新增 P43–P46）

**P43 分块可证承诺律（Certifiable Chunk Commitment）**
执行器只提交认证前缀 `L* = min(L_safe, L_obs, L_energy, L_stitch, L_therm)`，其中 `L_safe` 为管道驻留自由空间的步数、`L_obs` 为所依赖 AbsCert/CertBox 的最早 TTL 剩余步数、`L_energy` 为能量不变量维持步数、`L_stitch` 为可从末端再锚定（停或新块）的步数、`L_therm` 为热包络维持步数。整块 `A` 只用于推理摊销；**绝不执行超过 `L*` 的前缀**。`L* < L_min`（如 1 步）时不提交该块，退回 v22 的逐步执行。故 ACC 只裁短、不新增可达点。

**P44 功率约束储备律（Power-Constrained Reserve Viability）**
储备不变量必须**能量-功率-热三重可行**：对承诺窗口内所有 `t`，
`E_res^lo(t) ≥ E_fallback(t) + E_reach_safe^lo(t) + E_arm(t) + E_margin`
且 `P_fallback(t) ≤ P_avail_max(SoC^lo(t), T^hi(t), SoH^lo)` 且（回馈制动）`P_regen(t) ≤ P_accept_max(SoC^hi(t), T^hi(t))` 且 `T_act(t) ≤ T_safe − ΔT`。任一失败即退出 `K_pow`：**能量足但功率不可行 ⇒ 判为不可行**，提前进入 SafeStop 或 CRLC，绝不把"焦耳够"当"停得下"。

**P45 估计不确定与退化单调律（Estimation-Uncertainty & Degradation Monotonicity）**
证书只使用保守界：`SoC^lo ≤ SoC_true ≤ SoC^hi`、`SoH^lo ≤ SoH_true`（置信 ≥1-β，来自 EKF 协方差/conformal/老化模型）。BSC 带有效期窗口 `[t, t+Δ_b]`，在 `|ΔSoC|>ε`、热事件、SoH 更新或换电时**强制失效重签**；换电使旧 BSC 立即作废（电池 ID 不匹配即拒绝）。退化只允许收紧 `K_pow`：`SoH' ≤ SoH ⇒ K_pow(SoH') ⊆ K_pow(SoH)`，禁止复用未重算的旧证书。

**P46 充电会合活性律（Charge-Rendezvous Liveness）**
若本地 SafeStop 在 `K_pow` 下功率不可行（如低电低温），系统不得静默死锁，而应求解一个认证会合方案 `π_r`：存在充电/安全态 `g` 使 `E_res^lo ≥ E_to(g) + E_stop_at_g + E_margin` 且全程功率可行；`π_r ∈ Fil_dcl`（遵守 v22 义务/禁区）。若无可行会合 ⇒ 立即受控 SafeStop 并升级告警。CRLC 只提供**回退目标**，不扩大执行域；其可达性判定并入 `L_stitch`，并加滞回带避免在会合可行/不可行边界振荡。

## 3. 与基线的接口（如何退化）

- ACC 失效（可达管道不可信/无法过近似）⇒ 不做块承诺，退回 v22 逐步执行 ⇒ 等价 v22；
- ACC 的 `L_obs` 变短（观测陈旧）⇒ 自动缩短承诺前缀，只更保守；
- BSC 失效（SoC/SoH 估计不可信、BMS 掉线）⇒ 用最保守界 `SoC^lo=0`（即全域按"随时可能没电"处理）⇒ 提前 SafeStop/会合，只收紧；
- 功率界不可得（`R_int`/`V_oc` 标定缺失）⇒ `P_avail_max=0` 视为不可行 ⇒ 退到 v22 的"能量+人距上限"静态慢速模式，只收紧；
- CRLC 失效（无会合解）⇒ 直接受控 SafeStop（可审计）⇒ 子集；
- 换电/SoH 骤降 ⇒ 所有依赖旧 BSC 的计划作废重签 ⇒ 只收紧；
- 全部失效 ⇒ 完全回退 v22 ⇒ `Exec_v23 ⊆ Exec_v22 ⊆ Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19 ⊆ Exec_v18`。
- **安全继承**：ACC 只裁短前缀、BSC 只收紧预算与缩短有效期、CRLC 只给回退目标、K_pow 只交不并；任意失效都向更保守方向退化。

## 4. 预期贡献

1. **分块承诺证书 (ACC)**：首次把动作分块的"块"变成可审计的安全时间单元，给出"可承诺前缀 `L*` = 五重有效期最小值"的构造与接缝归纳，使"长块推理 + 短前缀承诺"成为可证协议；
2. **功率可行生存核 (K_pow)**：指出并形式化"能量够 ≠ 功率够 / 充满反而刹不住"的回退失效模式，把能量账户升级为能量-功率-热三重可行的储备不变量；
3. **估计不确定与退化单调**：把 SoC/SoH 的置信界与换电/老化事件纳入证书生命周期，给出"退化只收紧、换电即作废"的单调重签机制与 merkle 审计；
4. **充电会合活性 (CRLC)**：给 v22 的活性坍缩一个可证的出口——本地回退不可行时以认证会合替代静默死锁；
5. **时序一致性探针**：重叠预测不一致作为模型/感知漂移的免费监控，并可接入 CFC++ 的层级一致性检查；
6. **HPC-EC 统一准入门**：HPC-E ∪ ACC ∪ BSC ∪ CRLC，`Exec_v23 ⊆ Exec_v22` 闭环。

## 5. 本轮最大风险

**一句话**：`L*` 的正确性同时押在"可达管道过近似确实包住真实状态"与"SoC/SoH/内阻功率模型在低温、老化、换电后仍然可信"这两个经验前提上；一旦管道低估或功率界在高负载/低温下失准，`L*` 会被系统性高估，机器人就会在一个"已认证"的盲承诺窗口里滑向无法回退的境地——把"可证分块"变成"可证的鲁棒性幻觉"。

## 1. 关键算法骨架

```python
# IP-436 Action Chunk Certificate：块 -> 管道 -> 认证前缀
@dataclass
class ActionChunkCertificate:
    A: list                     # 动作序列 (a_t..a_{t+H-1})
    R: list                     # R[k] ⊇ 第 k 步可达集（区间/zonotope 过近似）
    H: int
    L_min: int = 1

    def safe_prefix(self, free_space):
        # L_safe：管道驻留认证自由空间的最大步数
        L = 0
        for k in range(self.H):
            if issubset(self.R[k], free_space[k]):
                L = k + 1
            else:
                break
        return L

    def observation_prefix(self, relied_certs, now):
        # L_obs：所依赖证书的最早剩余 TTL（步），陈旧观测立即缩短承诺
        ttl = [c.ttl_remaining(now) for c in relied_certs]
        return max(0, min(ttl) if ttl else 0)

    def thermal_prefix(self, bsc):
        # L_therm：热包络维持步数，交由 BSC 预测轨迹
        return bsc.thermal_prefix(self)

    def stitch_prefix(self, S_handoff, bsc):
        # L_stitch：末端须落在交接安全集 S_handoff ∩ K_pow
        L = 0
        for k in range(self.H):
            if self.R[k] <= S_handoff and bsc.all_in_viable(self.R[k]):
                L = k + 1
            else:
                break
        return L

    def certified_prefix(self, free_space, relied_certs, bsc, S_handoff, now):
        L_safe = self.safe_prefix(free_space)
        L_obs = self.observation_prefix(relied_certs, now)
        L_energy = bsc.energy_prefix(self)
        L_pow = bsc.power_prefix(self)
        L_therm = self.thermal_prefix(bsc)
        L_stitch = self.stitch_prefix(S_handoff, bsc)
        L_star = min(L_safe, L_obs, L_energy, L_pow, L_therm, L_stitch)
        # 推论 A：L* 只会被裁短；不足 L_min 则拒绝提交该块（退回 v22 逐步）
        return L_star if L_star >= self.L_min else 0


# IP-437 Battery State Certificate：保守界 + 有效期 + 换电/退化重签
@dataclass
class BatteryStateCertificate:
    battery_id: str
    bms_firmware: str
    calib_hash: str
    soc_lo: float; soc_hi: float     # 来自 EKF 协方差 + conformal，置信 >=1-beta
    soh_lo: float
    t_issue: float; delta_b: float
    T_act_hi: float
    merkle_root: str

    def valid(self, now, battery_id_now, soc_now, event):
        # P45：有效期 + 换电 + 显著 SoC 变化 + 热/SoH 事件
        if now > self.t_issue + self.delta_b: return False
        if battery_id_now != self.battery_id: return False
        if event in ("THERMAL", "SOH_UPDATE", "BATTERY_SWAP"): return False
        if abs(soc_now - self.soc_lo) > 0.05: return False
        return True

    def power_ok(self, plan_fallback, T_traj_hi):
        for t, (p_dem, p_regen) in enumerate(plan_fallback.power_demand()):
            if p_dem > self.p_avail_max(self.soc_lo, T_traj_hi[t], self.soh_lo):
                return False
            if p_regen > self.p_accept_max(self.soc_hi, T_traj_hi[t]):
                return False
        return True

    def p_avail_max(self, soc_lo, T_hi, soh_lo):
        voc = self.V_oc(soc_lo)
        rint = self.R_int(soc_lo, T_hi, soh_lo)
        return max(0.0, self.V_min * (voc - self.V_min) / max(rint, 1e-9))

    def p_accept_max(self, soc_hi, T_hi):
        # 高 SoC 回馈受限：接近满电时受电功率收敛
        return max(0.0, self.P_chg_limit * (1.0 - soc_hi) + self.P_chg_floor)

    def energy_prefix(self, chunk):
        E = self.energy_available(self.soc_lo, self.soc_floor)
        consumed = 0.0
        for k in range(chunk.H):
            consumed += chunk.energy_step(k)
            if E - consumed < self.reserve_required(chunk, k):
                return k
        return chunk.H

    def power_prefix(self, chunk):
        # 与 energy_prefix 取小：能量够但功率不够也在此被截断
        for k in range(chunk.H):
            if not self.power_ok(chunk.fallback_from(k), chunk.T_traj_hi(k)):
                return k
        return chunk.H

    def reserve_required(self, chunk, k):
        # P44：回退 + 到达安全态 + 臂能耗 + 裕度（全部用保守上界）
        return (chunk.E_fallback(k) + chunk.E_reach_safe_lo(k)
                + chunk.E_arm(k) + self.E_margin)


# IP-438 Power-Constrained Viability Kernel
class PowerConstrainedViabilityKernel:
    def __init__(self, bsc, evc):
        self.bsc, self.evc = bsc, evc

    def contains(self, x, v, z, t):
        # 四重可行：能量 ∧ 放电功率 ∧ 回馈受电 ∧ 热包络
        if self.bsc.energy_available(self.bsc.soc_lo, self.bsc.soc_floor) < \
           self.bsc.reserve_required_at(x, v, z):
            return False
        fb = self.evc.fallback_plan(x, v, z)
        if not self.bsc.power_ok(fb, fb.T_hi_traj):
            return False
        return self.bsc.T_act_hi <= self.bsc.T_safe - self.bsc.delta_T


# IP-439 Charge-Rendezvous Liveness Certificate
class ChargeRendezvousLivenessCertificate:
    def __init__(self, planner, bsc, dcl, pcvk, hysteresis=0.05):
        self.planner, self.bsc, self.dcl = planner, bsc, dcl
        self.pcvk = pcvk
        self.hyst = hysteresis
        self.last_feasible_E = None

    def solve(self, x, candidates_g):
        best = None
        for g in candidates_g:
            pi = self.planner.plan_to(x, g)              # 计划到会合目标
            if pi is None or not self.dcl.admits(pi):    # 遵守 v22 义务/禁区
                continue
            need = pi.E_to() + pi.E_stop_at(g) + self.bsc.E_margin
            if self.bsc.energy_available(self.bsc.soc_lo, self.bsc.soc_floor) < need:
                continue
            if not self.bsc.power_ok(pi.fallback_traj, pi.T_hi_traj):
                continue
            best = pi
            break
        # 滞回：避免在可行/不可行边界抖动
        if best is None:
            if self.last_feasible_E is not None and \
               self.bsc.energy_available(self.bsc.soc_lo, self.bsc.soc_floor) > \
               self.last_feasible_E * (1 - self.hyst):
                return ("HOLD", None)
            return ("SAFE_STOP", None)
        self.last_feasible_E = self.bsc.energy_available(self.bsc.soc_lo, self.bsc.soc_floor)
        return ("RENDEZVOUS", best)


# IP-440 Chunk-Boundary Handoff Invariant
def handoff_ok(chunk_prev, L_prev, chunk_next, pcvk):
    # 交接不变量：前一前缀末端整块落在 S_handoff，且下一块从该集内签发
    end_tube = chunk_prev.R[L_prev - 1]
    return end_tube <= chunk_next.S_handoff and chunk_next.starts_within(end_tube) \
           and pcvk.contains_set(end_tube)


# IP-441 Temporal Chunk Consistency Monitor
class TemporalChunkConsistencyMonitor:
    def __init__(self, tau_chunk):
        self.tau = tau_chunk
        self.prev = None

    def inconsistent(self, A_now):
        if self.prev is None:
            self.prev = A_now
            return False, 0.0
        overlap = min(len(self.prev), len(A_now))
        delta = max(abs(self.prev[k] - A_now[k]) for k in range(overlap))
        self.prev = A_now
        return delta > self.tau, delta     # 超标 -> 调用方缩短 L* 并告警


# IP-442 HPC-EC：v22 的 HPC-E 原样保留，只加时序-储能门
@dataclass
class HPCEC:
    hpc_e: HPCE
    acc_ok: bool
    bsc_ok: bool
    crlc_ok: bool

    def admits(self, plan, L_star, bsc, crlc_state):
        return (self.hpc_e.admits(plan) and
                self.acc_ok and L_star >= 1 and
                self.bsc_ok and bsc.valid(now(), battery_id_now(), soc_now(), event) and
                self.crlc_ok and crlc_state in ("RENDEZVOUS", "HOLD", "NOT_NEEDED"))
```

## 2. 推导

**引理 170（能量-功率反例）** 存在电池状态 `(SoC, T, SoH)` 与回退计划 `π_fb` 使 `E_res ≥ E_fb + E_reach + E_margin`（v22 EVC 放行），但对某 `t` 有 `P_demand(t) > P_avail_max(SoC^lo(t), T^hi(t), SoH^lo)`，于是 `π_fb` 在该步不可执行。故能量可行 `K_energy ⊉` 可安全停下；必须用 `K_pow ⊆ K_energy`。对称地，高 SoC 时 `P_regen(t) > P_accept_max(SoC^hi,T^hi)` 使回馈制动失效、制动距离变长，亦被 `K_pow` 拦截。∎

**引理 171（认证前缀的可靠性）** 设对每个 `k < L*`：管道过近似 `R_k ⊇ 真实可达_k`、所依赖证书剩余有效期 `> k`、保守界满足 `SoC_true ∈ [SoC^lo,SoC^hi]`、`SoH_true ≥ SoH^lo`、`T_true ≤ T^hi`。因 `L* ≤ L_safe` 得 `R_k ⊆ F_k`（无碰撞）；因 `L* ≤ L_obs` 得观测假设在承诺期内不失效；因 `L* ≤ L_energy,L_pow,L_therm` 得回退能量/功率/热全程可行；因 `L* ≤ L_stitch` 得末端可再锚定。取各事件联合界，执行前 `L*` 步以 `≥1−(δ_tube+δ_obs+δ_bat+δ_th)` 保持认证安全。`L*` 是五个独立上界的 `min`，任一项变保守都只会缩短执行前缀，故单调。∎

**引理 172（分块接缝归纳）** 设块序列 `A^{(1)},A^{(2)},…`，第 `i` 段只执行认证前缀 `L*_i`，且交接不变量成立：`R_{L*_i}(A^{(i)}) ⊆ S_handoff`，下一块从 `⊆ R_{L*_i}` 内的状态签发（`starts_within`）。基例：首段由引理 171 安全。归纳：若前 `i` 段安全且末端状态 `∈ S_handoff ∩ K_pow`，则第 `i+1` 段从该集内签发，由引理 171 安全，末端仍 `∈ S_handoff`。故整条拼接轨迹安全，接缝处无缝隙。若某步 `handoff_ok` 失败则停止提交新块并进入 SafeStop/CRLC，安全不破。∎

**引理 173（功率界的退化单调）** 对 `SoH' ≤ SoH`，有 `R_int(·,SoH') ≥ R_int(·,SoH)`、`Q_eff' ≤ Q_eff`，故 `P_avail_max(·,SoH') ≤ P_avail_max(·,SoH)`、`E_available(·,SoH') ≤ E_available(·,SoH)`，于是 `K_pow(SoH') ⊆ K_pow(SoH)`。换电使 `battery_id` 不匹配，BSC 直接失效；未重算的旧证书不被复用。故退化/换电只收紧执行域。∎

**引理 174（会合的活性与安全）** 若 `CRLC.solve` 返回 `RENDEZVOUS`，则存在 `π_r ∈ Fil_dcl` 使能量与功率双预算可达目标 `g` 且能停住，故系统可从"本地回退不可行"过渡到认证安全态，避免静默死锁；若返回 `SAFE_STOP`，则执行 v22 已有的受控停机。滞回带 `hyst` 保证判定不在边界抖动，故活性恢复不引入振荡。`π_r` 不新增 v22 之外的可达点，只替换回退目标。∎

**引理 175（v23 整体安全继承）** 同一几何快照、同一 v22 状态、同一电池估计与规则库下：ACC 只裁短提交前缀（171/172）、BSC 只收紧预算与缩短有效期（173）、PCVK 只交不并（170）、CRLC 只替换回退目标或在无解时停机（174）、TCCM 只在漂移超标时缩短 `L*`。故 `Exec_v23 ⊆ Exec_v22 ⊆ Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19 ⊆ Exec_v18`。∎

## 6. 已知风险与失效模式

1. **管道过近似低估**（最大风险之一）：可达集过近似若不够保守，`L_safe/L_stitch` 被高估 → 盲承诺。缓解：区间/zonotope 保守膨胀 + 扰动集在线辨识 + 高估率=0 判据（E836–E838）。
2. **电池模型失准**：低温/老化/高负载使 `V_oc/R_int` 偏离，`P_avail_max` 高估。缓解：保守查表 + 温度补偿 + 换电/热事件重签（E841–E846）。
3. **SoC/SoH 估计偏差**：点估计乐观 → 用置信下界，事件触发重校准（E843/E844）。
4. **接缝设计不当**：`S_handoff` 过松导致接缝缝隙，过紧导致活性坍缩。缓解：CBHI + E838/E858。
5. **CRLC 边界振荡**：在"会合可行/不可行"间来回切换。缓解：滞回 + E849。
6. **计算延迟**：块级管道与功率预测侵入控制环。缓解：10Hz 事件化，控制路径只查 O(1) 缓存（E860）。
7. **审计成本与隐私**：`ζ_tempo` 长期留存电池/标定哈希。缓解：最小化留存、只存哈希与证书（E861/E862）。

## 7. 本轮最大风险

**一句话**：`L*` 的正确性同时押在"可达管道过近似确实包住真实状态"与"SoC/SoH/内阻功率模型在低温、老化、换电后仍然可信"这两个经验前提上；一旦管道低估或功率界在高负载/低温下失准，`L*` 会被系统性高估，机器人就会在一个"已认证"的盲承诺窗口里滑向无法回退的境地——把"可证分块"变成"可证的鲁棒性幻觉"。
