# 第 13 轮（承接第 10–12 轮）· REWIND：把量化省下的算力换成「可回退的记忆 + 可干预的容错」，在 180 秒内把失败变成重试

> 检索/复核日期：**2026-11-02（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新一轮灵感循环的第 1 轮，三个词是「容错控制」「长期记忆」「模型量化」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO；它补的是这三轮共同缺的**运行时资源层**：失败之后拿什么状态重试、长程任务靠什么记住、量化省下的毫秒到底该花在哪。

## 0. 先给结论：30% 不是「再准一点」，是「失败后没有第二次机会」

截至 2026-11-02，官网首页与榜单仍是 8 个模型：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。`runs.html` 现在有 256 行（8×32），但详情页仍是「测试视频占位，后续可替换为真实视频文件」；逐模型做 `step ~ success` 回归仍是 R²>0.999999，232/256 个成功率不是 10% 的整数倍，跨模型任务相关仍只有 0.0975。**结论不变：29.7% 是赛事方的预览上限/难度信号，不是可复现的 SOTA；但「榜首不到 30%」作为设计约束仍然成立。**

我这轮先做了一个可能改变方向的检查：**成功演示本身就不是「一次抓取、一次放置」**。对 HangCup / StackBowls / ZipUp 的 `file-000` 做夹爪开合事件统计（Dex1 量程 5.5 开、0.0 关，阈值取 2.75），结果：

| 任务 | 文件内 episodes | 右手 ≥2 次闭合 | 右手 ≥3 次闭合 | 右手中位数 |
|---|---:|---:|---:|---:|
| ZipUp | 369 | **94.3%** | **66.9%** | 3 |
| StackBowls | 412 | **68.9%** | 3.2% | 2 |
| HangCup | 719 | **13.9%** | 0.8% | 1 |

这不是说每次闭合都是「失败重试」——多物体任务本来就要多次抓。但它说明：**数据分布里本来就包含多段抓取、重抓、再对齐；而榜单测的是「一次 episode 里能不能最终成功」，不是「第一个 chunk 有多准」。** 一个只会开环执行 30 步 chunk 的策略，和一个会在失败后回退、重抓、再试的运行时，是在解两个不同的问题。

于是本轮的核心判断是：

> **30% 的天花板，可能不是「单次动作精度」的天花板，而是「一次性执行」的天花板。**

如果单次尝试成功率是 `p=0.25`，且重试近似独立，那么一个 episode 内允许 `k` 次尝试的上界是 `1-(1-p)^k`：k=2 → 43.8%，k=3 → 57.8%，k=4 → 68.4%。真实重试当然不独立：场景会被弄乱、时间会不够、重试成功率会下降。但这个上界足够说明**容错控制的边际收益可能远大于再训一个更大的 VLA**。180 秒的限制不是「只够做一次」，对 HangCup（平均 6.2s）这样的短任务，时间预算里理论上有很多次尝试；对 ToolboxStorage（37.6s）则只有几次。**重试必须被预算，而不是被禁止。**

三个灵感词在我这里不是三个模块，而是三个预算：

| 灵感词 | 它真正约束的东西 | 本轮的用法 | 不做什么 |
|---|---|---|---|
| **容错控制** | 时间/重试预算 | 故障分类 → 检测 → 分级恢复 → backtrack → 预算内重试/止损 | 不做第二个学习策略；不做「报警就 reset」 |
| **长期记忆** | 上下文/带宽预算 | 事件索引的记忆 + 子目标进度 + 失败尝试 + 冻结的路线统计 | 不堆稠密视频历史；不做跨 episode 在线学习 |
| **模型量化** | 算力/延迟预算 | 保护动作头的混合精度；把省下的 GPU 时间换成多端口、快重规划、可回退 | 不做全模型 uniform INT8；不把量化当成功率本身 |

一句话：**先把 VLM 量化、把动作头保护住，再把省下的算力投到「更早发现失败、回退到可恢复状态、在 180 秒内再试一次」；记忆只记事件，不记整段视频。**

本轮的集成押注叫 **REWIND**：

> **R**ecoverable **E**vent-**W**itnessed **I**ntervention with **N**-step rollback and a quantized **D**eployment budget——用量化后的 WLA 做规划，用事件记忆保存「哪里、什么时候、什么物体、哪次尝试失败」，用可回退的容错阶梯把失败从终止条件变成一次 rewind。

三个可验证创新点：

1. **AQ-MP（Action-head-protected Mixed Precision）**：VLM 量化到 W8/W4，DiT action head、输出投影、robot-state projector 保持 BF16/FP16；用 chunk-aware 校准和闭环单任务 A/B 选精度，不只看权重 MSE。目标：显存 12.46GB → 4–7GB，p99 加速 1.5–2.5×，让 1 张 24GB GPU 服务 2–3 个端口，或让重规划从 300ms 降到 150ms 量级。
2. **EM-RING（Event-Memory Ring + backtrack buffer）**：episode 内只存任务相关事件（首次看见、抓取闭合、滑移、放置、人为移动、重定位）和最近 2–3 秒的 EE/夹爪轨迹；不存整段视频。事件用于重定位、子目标进度、失败尝试去重；backtrack buffer 用于回退到可恢复状态。离线再叠一层冻结的 route memory（哪个任务/相位用哪种策略成功率高），不在评测中在线学习。
3. **FT-LADDER（Recoverability-aware Fault-Tolerant Ladder）**：用本体跟踪残差、夹爪/物体刚性残差、视觉质量、chunk 一致性、进度停滞、延迟尖峰做确定性检测；报警后不是立刻 reset，而是按 L0 继续 → L1 降速 → L2 重定位 → L3 重抓/重放 → L4 backtrack → L5 重规划 → L6 salvage → L7 让行/安全停 的阶梯，在共享 180 秒预算内选动作。关键不是「检测得多准」，而是 **RESCUE 式地问：这个报警真的值得干预吗？**

第四个点不是新模块，而是把它们串起来的 **BUDGET-ORCH**：一个 episode 级调度器，按任务时长、当前进度、剩余时间、失败次数决定「继续 / 回退 / 重试 / 止损 / 保步骤分」。没有它，量化、记忆、容错会互相抢预算。

## 1. 本轮新核实/修正的事实（只列会改变方案的）

### 1.1 身份与规则：仍是宇树，未发现更强的其他 UniBot 指向（A）

本轮重新抓取官网、挑战赛页、排行榜、`runs.html`、提交仓库、HF 数据集集合；所有入口都指向 Unitree G1 + Dex1 的 UniBot-V1。用 Bing 搜「UniBot 机器人」也没有出现比宇树更强的赛事指向。因此按宇树展开；如果用户指的是另一家 UniBot，本轮结论需要重做。

规则（中文/英文参赛手册，2026-11-02 复核）：

- 所有任务须基于**同一模型**完成，不得混合多个模型；模型类型不限（World Model、VLA 均可）。
- 32 个任务，每任务 10 次独立运行；5 类泛化各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
- 单次真机执行上限 **180 s**；排名先看 32 任务总平均成功率，再相同看总平均步骤分，再相同看更早提交。
- 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立，`reset()` 状态隔离。
- 另有**不计分的单任务测试通道**，可用于单任务成功率/步骤分验证。

这四条直接约束本轮：容错/记忆/量化都必须是**每端口独立、CPU 轻量、不抢 GPU、不新增学习策略**的运行时；重试必须围绕 180 秒做预算；单任务通道是唯一敢做 A/B 的地方。

### 1.2 API：`obs_delta_indices` 原生支持时间堆叠，但 chunk 仍是固定开环（A）

提交模板（2026-11-02 复核）给出的观测是四路 RGB 480×640、双臂关节 `[7]`、EE 位姿 `[6]`、夹爪 `[1]`、下身体 `[15]`、语言 `str`；动作 `joint`/`ee` 互斥，`action_chunk_size` 在 handshake 时固定，evaluator 执行完整个 chunk 才再次调用。没有 depth、camera_info、force/torque、tactile。

本轮最重要的接口修正是：**`obs_delta_indices` 不只是选 key，它还决定时间堆叠。** 官方 `example_policy.py` 用的是：

```python
IMAGES: [-10, -5, -2, 0]   # 4 帧，跨度 10 步 ≈ 333ms
STATES: [-4, -2, 0]        # 3 帧
```

这比第 12 轮假设的 `[0]` 更接近「原生短期记忆」。但要注意：

- 堆叠的是**固定偏移的过去帧**，不是任意事件关键帧；要保留「30 秒前物体在哪」必须靠策略内部记忆。
- 每多一帧就是多一份图像传输/编码成本；4 路 ×4 帧在 30Hz 下很贵，必须配合 `image_resize` 和稀疏偏移。
- 官方 WLA 的 model server 目前对每个 key 只取 `_last_frame`；**原生 API 的时间堆叠不会自动变成 WLA 的长期记忆**，要么改 obs adapter/action head，要么把记忆放在 WLA 外部的检索/状态机里。

另一个关键细节：挑战赛 `ee` 动作是 base 系**绝对目标位姿**；WLA 输出的是相对当前 EE 的 xyz+rotvec。adapter 必须先把整个 30 步 compose 成绝对目标，再切片；否则第 6–30 步会以错误锚点解释。

### 1.3 数据：33,276 条 / 169.28 h；本轮修正第 12 轮「腕部没有内参」的错误（A）

32 个 HF 数据集合计仍是 **33,276 episodes / 18,282,246 frames / 169.28 h @30fps**（上轮逐数据集复核；本轮抽查 HangCup：1043 episodes / 194,564 frames / 30fps；集合 `lastUpdated=2026-09-11`，各数据集 `lastModified=2026-10-14`）。

**修正**：第 12 轮写「腕部相机没有内参矩阵」。本轮直接读 HangCup 的 `meta/info.json`，`wrist_left.color` / `wrist_right.color` 都有完整的 `camera_matrix`、`dist_coeffs`、`width/height`、`model`：

| 相机 | fx | fy | cx | cy |
|---|---:|---:|---:|---:|
| wrist_left.color | 436.41 | 435.92 | 323.92 | 242.93 |
| wrist_right.color | 435.12 | 434.50 | 319.02 | 240.99 |

腕部 IR 双目还有 18.0–18.05 mm 的基线和 `extrinsics_to_color`。这意味着 CHUNK-SERVO 的 G0 应从「一次性棋盘格标定」降级为「验证内参/外参是否与真机一致」；腕部 2D 伺服比第 12 轮估计的更可行。**但不要假设所有数据集/所有机器人批次完全一致，仍要做一次重投影校验。**

数据还有两个对记忆/容错有用的细节：

- `action.pivot` 7 维在数据集 README 中给出 `vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height`；线上 API 只写「Lower-body / pivot target」。adapter 必须先用 `example_env.py`/单任务通道验证符号和顺序，不能猜。
- 任务平均时长 6.2s（HangCup）–37.6s（ToolboxStorage）。这直接决定每个任务的「重试预算」不同；不能用同一个 `k_max`。

### 1.4 官方 WLA：6B、12.46GB、30 步、4 步去噪，且 server 只取最后一帧（A）

- 权重 `model.safetensors` 约 **12.46 GB**（BF16），6B 参数；单张 24GB GPU 可做 action-head 微调（冻结 VLM）。
- `action_horizon: 30`，`num_inference_timesteps: 4`；DiT-L 16 层、hidden 1024、32 heads、cross-attention dim 2560。
- 微调只训 DiT action head + robot-state projector；VLM 冻结。
- model server 的 obs 处理对每个 key 只取 `_last_frame`；所以官方 WLA 默认并没有消费 `obs_delta_indices` 的多帧历史。
- 54 维 WLA 动作 vs 挑战赛 `ee` 21 维（2×6 EE + 2×1 gripper + 7 pivot）；需要 adapter，且 `pivot` 语义是首个要验证项。

**战略含义**：量化 WLA 是可行的（12.46GB 有明确压缩空间），但「量化省下的时间」不会自动变成「更好的控制」——因为官方 server 是 30 步 chunk、4 步去噪、只取最后一帧。要把它变成控制收益，必须在**调用频率、重规划、记忆条件、端口并发**上重新分配。

### 1.5 榜单仍是预览，不能当失败分布（A+B）

| 证据 | 结果 |
|---|---|
| `leaderboard_data.json` 的 `generated_from` | `gen_leaderboard.py` |
| 8 模型 ×32 任务 `step ~ success` 回归 | R² > 0.999999，最大残差 <0.006 |
| 256 个任务成功率中非 10% 整数倍 | **232 / 256** |
| 8 模型 32 维任务成功率两两平均 off-diagonal 相关 | **0.0975** |
| 详情页视频 | 全部「测试视频占位」 |

因此：29.7% 只能当「赛事方预览上限/难度信号」，不能当 SOTA、不能当任务难度表、不能反推失败类型。本轮不从榜单任务排名挖创新点；只用它说明「所有模型共享一个一次性执行瓶颈」。

### 1.6 成功演示里的多段抓取：容错不是补丁，是数据分布的一部分（B）

本轮对三个任务的 `file-000` 做了夹爪事件统计（阈值 2.75；只统计动作流，不是真值失败标签）：

| 任务 | episodes | 右手 ≥2 次闭合 | 右手 ≥3 次闭合 | 右手中位数 | 右手中最大 |
|---|---:|---:|---:|---:|---:|
| ZipUp | 369 | 94.3% | 66.9% | 3 | 5 |
| StackBowls | 412 | 68.9% | 3.2% | 2 | 3 |
| HangCup | 719 | 13.9% | 0.8% | 1 | 4 |

解释要谨慎：

- ZipUp 的多次闭合可能包含拉拉链的多段动作；StackBowls 可能包含逐个叠碗；HangCup 的多次闭合更可能是重抓。
- 但无论原因是「多物体」还是「重试」，**成功轨迹里存在多段抓取/重抓**。一个只输出单段 30 步 chunk 的策略，必须在 chunk 边界重新观察才能衔接；一个带记忆和容错的运行时，可以把「上一次抓空了」变成「回退 2 厘米再抓」。
- 这也解释了为什么「平均成功率 30%」和「平均步骤分 1.3× 成功率」会同时出现：模型经常完成了一部分，但在最后一段没有第二次机会。

### 1.7 文献：三个词都已有强前置，但没人按本赛事约束组合（A）

**量化（VLA）**

- **SACQ**（arXiv 2610.41408，2026-10-30）：GR00T N1.7 在 1.5 bit/权重下 LIBERO 平均 93.85%，显存降 4.83×；INT8 激活 + 低精度注意力仍 93.55%，比 BF16 快 1.51×。
- **QbD-VLA**（2610.38661，2026-10-28）：用短闭环任务成功率做混合精度分配；约 4-bit 权重、<6-bit 激活；但在 Franka 上「仿真选的分配」对 X-VLA 无损、对 π0.5 失败——**闭环真机验证不可省**。
- **AGQ**（2610.33074，2026-10-21）：W3 在 LIBERO 92.7%，W2.5 70.5%，W1.5* 25.5%，6.10× 压缩。
- **CHASE-VLA**（2610.02666，2026-10-02）：chunk-aware 的 action expert PTQ，W4A4 双 MLP/attention，π0.5 上 97.3%，AE 权重存储降 73.4%。
- **VLAQuantBench**（2609.25376，2026-09-21）：π0.5 action-head 子集从 126 层扩到 167 层，W4A4 成功率从 **7.0% → 70.5%**；保护一个 28,672 参数输出投影就能让 OpenVLA-OFT 回到近基线。**动作头精度是主要矛盾。**
- **SmolVLA ONNX**（2609.14146，2026-09-12）：请求的 FP16/INT8 ONNX 把 p99 从 1181ms 降到 601/532ms，但 Spatial 成功率从 70% 掉到 41/40%；图审计发现所谓 INT8 产物其实是 FP32 图；语言上下文宽度 16/24/32 对应 41/75/71%。**「量化了但没真量化」和「上下文宽度」都是坑。**
- **VLA-HWBench**（2610.34717，2026-10-26）：18 个 VLA 在 Jetson Thor / AMD 上做七阶段拆解；动作生成策略比模型大小更决定延迟（14/19 Jetson 配置），参数只解释 ≤15% 延迟方差；4-bit 权重 + kernel fusion 对 π0.5/GR00T N1.7 快 2.6–2.9×；优化后 CPU 预处理从 12% 涨到 39%。**量化前先做阶段拆解，否则可能优化错瓶颈。**
- **Q-WAM**（2609.33269，2026-09-27）：4-bit World Action Model，用 Action Observability Gramian + Action-Subspace Protection 保护动作敏感子空间。说明世界模型路线也在走「动作子空间保护」，不是 uniform 低比特。

**长期记忆**

- **WholeBodyMem / HuMeGo**（2610.31166，2026-10-22；代码 `crystalccy1/MemoryBeforeGoal`）：Unitree G1 的 6 个仿真 + 6 个真实记忆任务；用对象事件选关键帧，成功从 29.1%→72.6%（仿真）、36.7%→88.3%（真机）。**记忆的收益可以非常大，但它用的是 SAM3 + 记忆增强 action expert；我们不能直接照搬多模型。**
- **CogMemory**（2610.34251，2026-10-25）：3.45M 参数的变分认知记忆，多槽时间抽象 + 门控融合；轻量、可插到多种 VLA backbone。
- **PAL**（2610.29329）与 **EventSync**（2610.27917）：分层记忆 + 子目标完成检测；RoboMME 上 56.05% / 64.5%。它们需要 VLM planner；我们可以用离线任务图替代，避免第二个模型。
- **Long-WAM**（2610.10528，2026-10-07）：上下文从 0 到 19.2s，RoboCasa GR-1 成功率 63.3%→78.7%；RTX 5090 每 chunk 107.4ms；已在 Unitree G1 部署。**历史不是越长越好，而是「自回归预训练 + 稀疏关键帧」才有效。**

**容错/恢复**

- **FRAMES**（2609.22538，2026-09-18）：Unitree G1 的失败监督框架；Monitor 在 MuJoCo 100 次试验中检出 48/50 失败、接受 46/50 成功，94% 准确率；但它用 VLM Monitor + Planner/Recovery Agent，**多模型**。
- **VLA-Corrector**（2609.06508，2026-09-06）：冻结 VLA + Learned Verifier + 阶段条件 prompt 恢复，不改参数；Learned Verifier 接近特权规则 verifier。**思路可用，Learned Verifier 不能直接用。**
- **Recova**（2610.01178，2026-10-01）：数字孪生里诊断/测试恢复程序，部署时监控 + 恢复 + 验证；LIBERO-Pro 78.8% vs 71.7%，MolmoSpaces 64.9% vs 38.0%。
- **Backtrack**（2610.32941，2026-10-23）：冻结 VLA + 0.48–0.88% 参数的失败预测头；报警后暂停、沿最近运动回退、把控制交回原策略重试；LIBERO-Long 失败率降 19–48%，成功率最高 +7.4pp，三个短 suite 收益小。**这是本轮最接近「回退重试」的前置工作。**
- **Progress Probes P²**（2610.31613，2026-10-22）：在 VLA 内部激活上训线性 probe 估计进度，效果不输 VLM monitor，且不需要外部模型。**单模型合规的检测路线。**
- **RESCUE**（2610.13516，2026-10-09）：用反事实分支评估「报警是否值得干预」；128,340 条分支；在 stop-and-reset 模型下，即使理想检测器也只能承受 **2.0–3.3% 的误报**，否则无谓 reset 的成本超过收益。**检测准确率 ≠ 干预价值；这是本轮 FT-LADDER 的核心约束。**
- **GUARD**（2608.04510，2026-08-05）：不改策略，用 KV cache 消融测 grounding；跨任务 ROC-AUC 比最强 runtime monitor 高 5.73pp。**可作为 C3 备选，不作为首选。**
- **OSS**（2610.10810，2026-10-07）：长程任务 skill seam 的失败主要来自「场景状态被前一个 skill 改了」，不是机器人关节；BOSS-44 全链 7.6%→26.5%；真机受外视角可观测性限制，作者明确呼吁 wrist/gripper sensing。**记忆要记场景状态，不只是机器人状态。**
- **FreeBar**（2610.14997，2026-10-10）：训练-free 的 CBF 启发式 chunk 一致性约束，异步执行时对齐 committed stream。**可作为 chunk 边界安全滤波。**
- **REA**（2610.42053，2026-10-30）：「no running policy waits on the brain」；route memory + boundary-triggered judge gate + shared-budget escalation ladder；60 个 LIBERO-Pro 任务 95.9%。**它的运行时思想可直接借，但多策略组合不合规。**
- **Task-aware DMP**（2609.23151，2026-09-19）：接触密集 peg-in-hole 的阶段分类 + Mahalanobis 异常 + 恢复；用 goal-relative 特征泛化到未见目标位置。**接触任务的检测器可借鉴。**
- **TinyAstral**（2610.41216，2026-10-30）：harness 进化把 teacher 从 33.4% 提到 63.6%，蒸馏到 4B student 仍有 62.8%。**说明 runtime/harness 的收益可以超过模型规模；这与本轮押注一致。**

**没人做的事**：把「动作头保护的量化」「事件记忆」「recoverability-aware 容错阶梯」「180 秒预算」组合在一个单模型、N 端口、远程 API 的赛事约束下。现有工作要么是多模型（FRAMES、Recova、VLA-Corrector、REA、PAL/EventSync），要么只做离线量化（SACQ/AGQ/CHASE），要么只在仿真/LIBERO 验证（QbD 的真机 π0.5 已经失败），要么只做记忆不碰恢复（CogMemory/WholeBodyMem）。**组合本身就是创新点，但必须用单任务通道证明它不是「三个 trick 的堆叠」。**

### 1.8 头部方案的共同瓶颈：一次成功，而不是一次准确（A+B）

| 模型家族 | 公开路线 | 优势 | 与本轮相关的瓶颈 |
|---|---|---|---|
| MolmoAct2 | action reasoning + adaptive depth | 3D/空间语义强、推理快 | 仍是开环 chunk；没有失败回退/记忆的公开证据 |
| WALL-OSS-0.5 | 4B VLA（3B VLM + action expert） | 预训练可用；progress 高 | progress ≠ success；最后一步失败就 0 分 |
| DreamZero | 14B video-diffusion WAM | 长程预测 | 14B 推理重；量化/记忆都更贵；接触精度仍不解决 |
| π0.5 | 开放世界泛化 VLA | 语义/新场景 | 接触密集精度；远程延迟 |
| GigaBrain-0 | 世界模型生成数据 + VLA | 数据效率 | 生成数据物理保真度；运行时无恢复 |
| GR00T N1.5 | NVIDIA 通用人形 VLA | 生态/embodiment | 任务特定精度；数据覆盖 |

共同点不是「架构不够大」，而是：

1. **都是 one-shot chunk 执行**，chunk 内不看新图，失败后没有明确的「回退/重试」协议。
2. **都没有把「记忆」当成一等公民**；最多是短帧堆叠，长程/遮挡/人为移动靠模型隐式记。
3. **都没有公开「闭环量化」的部署证据**；量化论文多在 LIBERO/SIMPLER，且 QbD 已证明仿真选参会在真机 π0.5 上翻车。
4. **都在优化「第一次动作」，而不是「180 秒内的最终成功」**。

所以本轮不从「更强的 VLA」切入，而从**运行时**切入：用同一模型，把「失败」变成「可回退的状态 + 预算内的一次重试」。

## 2. 诊断：三个预算叠在同一个 episode 上

把一次 episode 拆开：

```text
t=0: 观测 → VLA 推理 → 30 步 chunk
t=0.1s: 开始执行 chunk（开环）
t=0.1–1.1s: 接触/滑移/人移动都发生在这一段
t=1.1s: 才看到下一帧
...
t=T_fail: 失败被检测到（可能已经过了不可逆点）
t=T_fail+Δ: 回退/重抓/重规划
```

三个预算：

1. **时间预算**：`180s`。重试次数 `k_max = floor((180 - T_setup - T_safe) / (T_attempt + T_recover))`。短任务 k 大，长任务 k 小；不能全局用一个重试次数。
2. **上下文预算**：`obs_delta_indices` 的帧数 × 图像分辨率 × 端口数。稠密历史会线性增加传输/编码/注意力成本；事件记忆应该只存「关键帧 + 结构化位姿」。
3. **算力/延迟预算**：`T_fb = H/f + τ`；`τ = T_pre + T_vlm + N_dit*T_dit + T_decode + T_net`。量化能降 `T_vlm`/`T_dit`，但如果 `T_pre`/`T_net` 占主导，收益会被吃掉（VLA-HWBench 已示警：优化后 CPU 预处理可从 12% 涨到 39%）。

三个「单独做会失败」的理由：

- **只做量化**：如果 VLA 每 30 步才调用一次，量化省下的 150ms 不会缩短 5 步伺服的反馈周期；它主要买的是**端口并发**和**故障后的快速重规划**。如果瓶颈在 CPU 预处理/网络，量化甚至不涨点。必须先做阶段拆解（G-Q0）。
- **只做记忆**：稠密历史增加 token/带宽，可能把 p99 推高；而且如果记忆不参与决策（只是多几帧输入），模型可能仍然忽略它。记忆必须和「重定位/子目标/失败去重」绑定。
- **只做容错**：检测准确不等于干预有价值。RESCUE 已经证明：在 stop-and-reset 模型下，理想检测器也只能承受 2–3.3% 误报；报警太晚、误报太多、回退碰撞，都会让容错变成负收益。

所以需要一个**共享预算的调度器**：它知道「现在还剩多少秒、失败了几次、回退要多久、重试成功率大概多少、步骤分还能不能保」，再决定动作。

## 3. 方法：REWIND 的四层

### 3.1 总架构

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port Runtime (CPU)             │
                    │  ├─ EM-RING (events + backtrack)    │
                    │  ├─ FT-LADDER (detect + recover)    │
                    │  ├─ BUDGET-ORCH (route + salvage)   │
                    │  ├─ CHUNK-SERVO (5-step servo)      │
                    │  └─ action adapter (WLA 54D → API)  │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared quantized WLA server (GPU)  │
                    │  VLM W8/W4 + DiT action head BF16   │
                    └─────────────────────────────────────┘
```

- 唯一学习模型：WLA（同一个 checkpoint，同一份权重，混合精度）。
- 记忆/检测/调度：确定性逻辑 + 离线检索；不加载第二个策略。
- 量化：同一 checkpoint 的不同精度/模块，不是第二个模型。
- 每个端口独立 `reset()`、独立事件环、独立预算；共享 GPU server 用 session ID 隔离。

### 3.2 AQ-MP：先保护动作头，再谈低比特

**动机**：WLA 12.46GB BF16；如果 VLM 降到 W8，显存约 6–7GB；W4 约 3–4GB。这样一张 24GB GPU 可以服务 2–3 个端口，或者在故障后并行跑一次重规划。但 VLAQuantBench 明确：π0.5 的 action-head 子集从 126 层扩到 167 层，W4A4 成功率从 7.0% 到 70.5%；动作头/输出投影是精度命门。QbD 又证明仿真选参会在真机 π0.5 上失败。

**做法**：

1. **阶段拆解**：先测 `T_pre / T_vlm / T_dit / T_decode / T_net` 的 p50/p99；如果 CPU 预处理或网络占主导，先优化 resize/JPEG/批处理，而不是盲目量化。
2. **模块分组**：VLM（Qwen）可 W8A8/W4A16；robot-state projector 和 DiT action head 保持 BF16/FP16；输出投影、最后 1–2 层、cross-attention 的 value/output 投影优先保护。
3. **动作感知敏感度**：对每组层，用 33k 演示的 action error（不是 weight MSE）估计量化后的 final-action error；按「每 MB 显存换多少 action error」做贪心分配。
4. **chunk-aware 校准**：校准数据包含完整 chunk（含未执行 suffix）和去噪步分组；不要只用当前帧/静态校准。
5. **闭环选参**：在单任务通道上，对 5 个代表任务做 `BF16 vs W8 vs W4-protected` 的短闭环 A/B；任务成功率优先，action MSE 只做筛选。QbD 的教训：仿真选参必须真机复核。
6. **图审计**：用 ONNX/TensorRT 的 graph inspector 确认真的有低比特 kernel；SmolVLA 的「INT8 其实是 FP32 图」不能再发生。
7. **预算再分配**：量化省下的 GPU 时间只花在三个地方——多端口并发、故障后快速重规划、更短的 chunk（如果 p99 允许）；**不要花在更多去噪步数/更大模型上**。

**预期**：显存 12.46GB → 4–7GB；p99 加速 1.5–2.5×；是否涨点取决于「省下的时间是否变成更早的干预」，不直接承诺成功率。

### 3.3 EM-RING：记忆是事件，不是视频

**动机**：WholeBodyMem 在 G1 上把记忆任务从 36.7% 提到 88.3%，但它用 SAM3 + 记忆增强 action expert；CogMemory 只用 3.45M 参数也能显著改善长程。我们的约束是单模型、远程 API、每端口 CPU 轻量。所以记忆必须是**结构化的、稀疏的、可检索的**，而不是把整段视频塞进上下文。

**四层记忆**：

| 层 | 存什么 | 生命周期 | 用途 |
|---|---|---|---|
| **事件环 EM-RING** | `{t, type, object_id, pose, keyframe(128×128), confidence}`；类型：first_seen / grasp_close / grasp_open / lift / slip / place / human_edit / reobserve | episode 内，环形，最多 32 条 | 重定位、失败去重、子目标进度 |
| **backtrack buffer** | 最近 2–3 秒的实测 EE 位姿、夹爪、物体位姿估计、动作 | episode 内，环形，90 帧 | 回退到可恢复状态 |
| **子目标图** | 离线从演示/任务描述得到的阶段序列、每阶段期望时长/传感器签名/恢复原语 | 冻结，随提交包 | 进度监控、prompt/检索条件 |
| **route memory** | 每任务/每阶段各策略（servo/backtrack/retry/salvage）的历史成功率/耗时 | 冻结，离线验证得到 | 预算内选路线；不在评测中在线更新 |

**关键设计**：

- **不存整段视频**。只存任务相关物体的关键帧（128×128 JPEG，约 5–10KB）和位姿；32 条事件 <1MB/端口。
- **事件触发更新**，不是每帧更新：抓取闭合、物体开始随夹爪动、物体停止、人进入/场景突变、重定位成功。
- **记忆参与决策的三种方式**：
  1. 重定位：目标被遮挡/人移动后，用最近事件的目标位姿 + 当前腕部图做局部匹配；
  2. 子目标：已完成/未完成的阶段决定 VLA prompt 或演示检索的 phase；
  3. 失败去重：同一物体、同一相对位姿、同一失败类型连续两次 → 不再原样重试，升级到 backtrack/replan。
- **API 映射**：`obs_delta_indices` 用最少当前帧（例如 `[0]`），策略自己维护事件环；如果要用原生堆叠，只给 2–3 个稀疏偏移（如 `[-10,-4,0]`），不要 4 路 ×4 帧全开。
- **可选记忆适配器**：如果 C1 不够，给 DiT action head 加一个 1–3M 参数的 cross-attention memory adapter，和 action head 一起训练；这仍是同一个 checkpoint（C2），不是第二个策略。

**为什么不是「长期记忆 = 更长上下文」**：Long-WAM 说明历史有帮助，但它的前提是自回归视频预训练 + 实时系统；直接把 19 秒帧堆进 WLA 会爆带宽/token。事件记忆是「用结构换长度」：只保留决策相关的事件，而不是所有像素。

### 3.4 FT-LADDER：报警不是目的，可恢复才是

**故障分类**（只列 API 能观测到的）：

| 类型 | 观测信号 | 典型任务 | 可逆性 |
|---|---|---|---|
| 抓空/未夹住 | 夹爪闭合但物体未随动；`r_grasp` 高 | HangCup、StackBowls | 高 |
| 滑移 | 物体相对夹爪位移；`r_grasp` 突变 | ZipUp、PlugInEthernet | 高 |
| 卡住/碰撞 | 指令 EE 与实测 EE 跟踪残差大；关节速度异常 | 插入、收纳 | 中 |
| 目标丢失/遮挡 | 双目有效视差低、特征 inlier 少、目标不在 ROI | 人为干扰、背景泛化 | 高 |
| 人为移动 | `edit_score` 高（静态/抓取模型都解释不了） | human 轴 | 高（让行） |
| 子目标错/循环 | 进度停滞、重复动作、chunk 不一致 | 长程任务 | 中 |
| 延迟尖峰/超时 | RTT/p99 超预算、返回形状异常 | 远程 API | 高（hold） |
| 不可逆风险 | 接近人、玻璃、液体、夹爪过载代理 | 倒药、插电 | 低（停） |

**检测器**（全部确定性，阈值从成功演示的 95/99 分位校准）：

```text
r_track   = || log(T_meas^{-1} T_cmd_prev) ||          # 跟踪残差
r_grasp   = || T_obj_meas - T_ee_meas * T_obj_ee* ||   # 抓取刚性残差
r_static  = || T_obj_meas(t) - T_obj_meas(t-Δ) ||      # 静止假设残差
edit      = min(r_static, r_grasp) 解释不了的物体运动  # 人为/场景编辑
chunk_dis = || a_new[0:H] - a_old[t:t+H] ||            # 新旧 chunk 重叠不一致
stall     = t - last_progress_time                     # 进度停滞
vis_bad   = disparity_valid < 0.7 or inliers < 15 or blur < θ
lat_bad   = p99_rtt > budget or timeout
```

**报警门控（RESCUE 式）**：

```text
V(alarm) = P(recoverable | alarm) * E[Δsuccess | recoverable] * V_success
         - P(false | alarm) * C_false
         - C_delay
```

只有当 `V(alarm) > 0` 且 `P(false) <= 5%`（backtrack）或 `<=2%`（reset/salvage）时才干预。检测 AUROC 只用于排序，不用于上线阈值；阈值用离线反事实分支选。

**阶梯**：

| 级别 | 动作 | 触发 | 成本 | 失败后 |
|---|---|---|---|---|
| L0 | 继续 | 无报警 | 0 | — |
| L1 | 降速/降增益/低通 | 轻微跟踪残差/接触 | 0.1–0.5s | L2 |
| L2 | 停 + 重定位（头双目/腕部/记忆） | 目标丢失、编辑 | 0.5–2s | L3 |
| L3 | 重抓/重放原语（同一 VLA 或脚本化） | 抓空/滑移 | 1–3s | L4 |
| L4 | backtrack：沿最近轨迹回退到可恢复点 | 卡住/连续失败 | 1–3s | L5 |
| L5 | 重规划（VLA + 记忆/prompt） | 子目标错/回退后 | 0.3–1s | L6 |
| L6 | salvage：完成安全子目标/保步骤分 | 成功概率低、时间紧 | 1–5s | L7 |
| L7 | 让行/安全停 | 人进入、不可逆风险 | 0–1s | 结束 |

**backtrack 细节**：

- 在最近 90 帧中选回退点 `b`：物体仍可见、无接触、跟踪残差低、回退时间可控。
- 逆序执行 EE 路径，低速度、限加速度；每 5 步重新检查跟踪残差和视觉质量。
- 到达后清空「本次失败尝试」的局部计划，但保留事件（失败去重）；把控制交回原 VLA，允许重试。
- 如果回退路径不可行（碰撞/超时），直接 L5/L6，不硬退。

**安全滤波**：关节限位/速度/加速度、工作空间包围盒、自碰撞胶囊、桌面高度先验；用 CBF 式一阶约束 `\dot h + αh >= 0` 投影动作。没有力/触觉，所以不声称力控；只用运动学 + 视觉代理。

### 3.5 BUDGET-ORCH：180 秒是投资组合

**状态机**（简化）：

```text
INIT → PLAN → EXECUTE ⇄ SERVO
                 │
                 ├─ alarm & V>0 → L1/L2/L3/L4/L5
                 ├─ progress stall → L5
                 ├─ time low & p_success low → L6
                 └─ human/irreversible → L7
```

**决策**：

```text
if remaining_time < T_safe: L7
elif success_prob > θ_s and remaining_time > T_needed: continue/retry
elif recoverable and V(alarm)>0: ladder
elif step_score_gain > cost: salvage
else: safe_stop
```

**每任务预算**（先验，单任务通道更新）：

- 短任务（HangCup 6.2s、StackBowls 10.1s、DisconnectEthernet 10.5s、FruitSorting 10.7s、FruitCollection 10.8s、ColorArrangement 13.6s、PaperCupStacking 13.9s、ZipUp 14.1s）：`k_max` 高，重试 ROI 高。
- 中任务（PlugCharger 15.1s、PackBag 15.1s、Syringe 15.3s、PickOutBattery 16.1s、PlugInEthernet 16.4s、ArrangeTestTubes 17.8s、PackDoll 19.6s、StoreCups 19.8s、OrganizePencilCase 20.5s、ArrangePlates 21.3s、PourOutMedicine 21.8s、OrganizeStationery 23.9s、StoreEarphones 24.1s、OrganizeTools 25s、FoldTowel 25.8s、PackPhone 29.2s、SpellRobot 31.2s）：平衡。
- 长任务（StorePaddle 34.1s、ToolboxStorage 37.6s）：`k_max` 低，优先记忆/一次做对/ salvage，不轻易回退。

**salvage 原则**：成功优先；只有成功概率低于阈值且时间不足时才保步骤分。不要为了步骤分放弃本可成功的重试。

### 3.6 合规分层：C1 首选，C2 备选，C3 不做

| 模式 | 组成 | 风险 | 建议 |
|---|---|---|---|
| **C1 无新权重** | WLA + 确定性检测/事件记忆/量化；记忆只做检索/状态机/servo 条件 | 最低 | **首选** |
| **C2 同 checkpoint 小模块** | 记忆 adapter / progress probe / failure head 与 action head 联合训练，仍在同一 checkpoint | 低–中；需说明 | 若 C1 检测不够再用 |
| **C3 外部模型** | SAM3/VLM monitor/第二个策略 | 高；单模型风险 | **不做**；只作为离线标注/教师 |

`reset()` 必须清空事件环、backtrack buffer、失败计数、当前计划；route memory 是磁盘上的冻结表，不随 episode 更新。**不做跨 episode 在线学习**，避免公平性/泄漏/“test-time training”争议。

## 4. 竞赛策略：把 320 trials 当投资组合，而不是 32 个独立任务

- **先锁基线**：WLA + adapter + chunk 5/8，单任务通道跑通 1 个任务；如果允许多次提交，先交安全基线锁「更早提交」tie-break。
- **A/B 只在单任务通道**：6 个代表任务——ZipUp（多抓取）、StackBowls（叠放）、HangCup（挂）、PlugInEthernet（插入）、FoldTowel（变形，防回归）、ToolboxStorage（长程）。每个 5 次配对：`BF16 vs W8`、`memory off/on`、`ladder off/on`、`chunk 5/8/30`。
- **通过标准**：至少 3/6 任务 +5pp；FoldTowel 不回归 >3pp；误报 ≤5%；p99 在预算内；无碰撞/超时上升。不到标准不烧正式提交。
- **正式 32×10 前**：N 端口干跑，检查 reset 隔离、内存不涨、p99、timeout；再跑全量。
- **不要做**：32 个任务各训一个策略；从零训 6B/14B；完整 world model；30Hz 广域网伺服；6D 物体位姿网络；力/触觉闭环（API 没有）；把预览榜单当难度表。

## 5. 与第 10/11/12 轮的关系：保留、升级、剪枝、修正

**保留**：

- FACT-VLA 的相位化 BC、CAC 柔顺、EGP 证据门控；
- GEO-RESIDUAL 的动作条件化残差、米制表面距离、编辑检测；
- CHUNK-SERVO 的双频执行、演示检索相对目标、数字孪生标定；
- 官方 WLA 基座、33k 演示、单任务通道。

**升级**：

- 固定 5 步伺服 → **预算选择的 chunk（3/5/8）**：先测 `T_fb` 和 p99，再选；不在线改。
- 绝对目标 → **事件记忆 + 相对目标**：目标被移动/遮挡后，从事件环重定位，而不是重新检索一张绝对图。
- 失败状态机 → **recoverability-aware 阶梯**：不是「报警就 reset」，而是先 backtrack，再重试。
- 量化从「部署细节」→ **一等公民**：动作头保护、闭环选参、阶段拆解、N 端口。
- 记忆从「帧堆叠」→ **事件 + 子目标 + route memory**。

**剪枝**：

- 跨 episode 在线学习（公平性/泄漏/合规风险）；
- 独立 Learned Verifier / 第二个策略 / SAM3 在线（单模型风险）；
- 稠密视频历史 / 全帧堆叠（带宽/延迟）；
- 全模型 uniform INT8/W4（动作头精度）；
- 从零训 VLA/World Model（官方 WLA 已做完）；
- 完整 sim-to-real 策略训练（只做控制器风洞）；
- 30Hz 广域网伺服（RTT 不允许）；
- 6D 物体位姿网络（透明/变形不可靠）；
- 力/触觉闭环（API 没有）；
- 32 个 per-task 策略（规则禁止）；
- 把预览榜单任务排名当难度表（已证伪）。

**修正**：

- 第 12 轮「腕部无内参」是错的；腕部 color 有完整内参，IR 双目有 18mm 基线。G0 改为验证，不是从零标定。
- 第 12 轮假设 `obs_delta_indices` 用 `[0]`；官方示例用多帧堆叠。记忆可以先用 API 原生堆叠做短期，再用内部事件环做长期。
- 第 12 轮把量化当「省钱」；本轮把它当「预算再分配」，且必须先做阶段拆解。

## 6. 实验门 G-Q/G-M/G-F/G-B

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G-Q0 | 延迟到底花在哪？ | 七阶段 p50/p99 可复现；知道 VLM/DiT/CPU/网络占比 | 先优化 CPU/网络，不量化 |
| G-Q1 | 量化是否真的快且不降点？ | 5 任务闭环：W8/W4-protected 与 BF16 差 ≤1–2pp；p99 加速 ≥1.5×；图审计通过 | 只 W8；保护更多层；放弃 W4 |
| G-M0 | 事件记忆是否可检索？ | 目标重定位误差 ≤2cm/5°；top-5 含有效事件 ≥80% | 退回 API 稀疏堆叠 |
| G-M1 | 记忆是否涨点？ | 3/6 长程/干扰任务 +5pp；短任务不回归 | 只保留离线分析 |
| G-F0 | 故障检测是否够早？ | 注入故障 AUROC ≥0.85；误报 ≤5%；检测 ≤200ms | 只保留高精度检测器 |
| G-F1 | 报警是否值得干预？ | 反事实 `V(alarm)>0`；3/5 任务 +5pp；无碰撞上升 | 关闭 reset/salvage，只做 backtrack |
| G-B0 | 预算是否守得住？ | 180s 内完成率 ≥95%；无超时；重试次数符合预算 | 降低 k_max；只做短任务重试 |
| G-I0 | 32 任务干跑稳定？ | N 端口隔离、reset 干净、内存不涨、p99 达标 | 回退基线 |
| G-Final | 是否真的比 CHUNK-SERVO 好？ | 32×10 干跑 +2–5pp；步骤分不降 | 只保留有效模块 |

统计：320 trials 下 `p≈0.25` 的单次标准误约 2.4pp；配对 A/B 用 bootstrap 95% CI；不要用 +1–2pp 下结论。

## 7. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定第二个模型 | C1 首选；C2 同 checkpoint 小模块并说明；不做 C3 |
| 量化降点 | 接触任务失败率上升 | 动作头 BF16；闭环选参；图审计；W8 保底 |
| 量化不加速 | 瓶颈在 CPU/网络 | G-Q0 先拆解；优化预处理/批处理 |
| 记忆带宽/token | p99 上升 | 事件稀疏；128×128；最多 32 条；不堆全帧 |
| 误报/晚报 | 无谓回退/错过窗口 | RESCUE 式 `V(alarm)`；阈值用反事实；误报预算 2–5% |
| backtrack 碰撞 | 安全/损坏 | 低速度、限加速度、CBF 滤波、路径检查、最大重试 |
| 时间预算 | 重试拖垮长任务 | 每任务 k_max；剩余时间门控；salvage |
| 记忆泄漏/隐私 | 公平性/合规 | 只存任务物体关键帧；不存人脸；reset 清空；不上传 |
| 跨 episode 学习 | 规则/公平性 | 禁止；route memory 冻结 |
| 评测噪声 | 假阳性 | 配对 A/B、bootstrap、重复；不用榜单反推 |
| 端口串扰 | 结果不可信 | 每端口独立状态；session ID；reset 测试 |

## 8. 一句话押注

**最值得押注的不是再训一个更大的 VLA，而是「AQ-MP + FT-LADDER」的组合：先把 WLA 的 VLM 量化、动作头保护住，把省下的 GPU 时间换成多端口和快速重规划；再用事件记忆保存可回退状态，用 RESCUE 式门控做 backtrack + 180 秒预算内重试——把一次失败变成一次可回退的再尝试。**

# 第 13 轮产物 · REWIND 技术报告

> 检索/复核日期：**2026-11-02（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「REWIND」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是把它们接到**运行时资源层**：容错控制决定「失败后怎么回退/重试」，长期记忆决定「回退到哪个状态、记住哪些事件」，模型量化决定「这些动作的算力从哪里来」。

## 0. 结论与边界

### 0.1 一句话结论

官方 WLA 的 30 步 chunk 和 6B 权重决定了「一次性执行」的成本结构；在 180 秒的 episode 里，真正稀缺的不是单次动作精度，而是**可回退的状态、可检索的事件、可承受的重试**。先做**动作头保护的混合精度量化（AQ-MP）**，把 VLM 压到 W8/W4、DiT 动作头留在 BF16，换来多端口和快速重规划；再用**事件记忆（EM-RING）**保存目标/尝试/进度，用**可恢复性感知的容错阶梯（FT-LADDER）**做 backtrack + 预算内重试；最后由 **BUDGET-ORCH** 在 180 秒内分配「继续 / 回退 / 重试 / 止损 / 保步骤分」。设计目标是在不新增学习策略的前提下，把一次失败变成一次可回退的再尝试，保守目标全局 +2–5pp，乐观 +5–8pp；必须用单任务通道配对 A/B 验证。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、排行榜 JSON 直接核实 | 规则、API、33,276 eps、WLA `action_horizon=30`、12.46GB、榜单 29.7% |
| B | 我们在公开数据/网页上做的分析，可复现 | 榜单 `step~success` 回归、夹爪开合事件统计、延迟预算推算 |
| C | 设计假设，需 G-Q/G-M/G-F/G-B 验证 | W8/W4 不降点、事件记忆 +5pp、backtrack 净收益为正 |

### 0.3 本轮不做什么

- 不从零训 VLA/World Model；官方 WLA-1.0 已开源 6B 基座。
- 不做第二个学习策略、独立 Learned Verifier、在线 SAM3；单模型风险。
- 不做稠密视频历史/全帧堆叠；事件记忆优先。
- 不做全模型 uniform INT8/W4；动作头必须保护。
- 不做跨 episode 在线学习；route memory 冻结。
- 不做完整 sim-to-real 策略训练；数字孪生只做控制器风洞。
- 不做 30Hz 广域网伺服、6D 物体位姿网络、力/触觉闭环（API 没有）。
- 不把预览榜单的任务排名当难度表（已证伪）。

> 命名说明：官网挑战赛页当前用 StorePaddle / StoreCups / PourOutMedicine / ArrangePlates / ConveyorSorting；榜单 JSON 与旧表用 Store Racket / Stack Cups / Open Pill Bottle / Clear Plates / Conveyor Food Sorting，指同一批任务。本报告以官网任务页为准，引用榜单时保留其别名。

**约束**：REWIND 必须每端口独立、CPU 轻量、不抢 GPU；容错/记忆/量化都不能是第二个策略。

1. `H=30`、30Hz → 一次 `get_action` 后有约 **1 秒开环执行**；chunk 内没有新观测。

## 2. 问题形式化

### 2.1 评分与重试

总分：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

若单次尝试成功率 `p`，一个 episode 内允许 `k` 次独立尝试的上界：

```math
p(k) = 1-(1-p)^k.
```

| p \ k | 1 | 2 | 3 | 4 |
|---:|---:|---:|---:|---:|
| 0.10 | 10.0% | 19.0% | 27.1% | 34.4% |
| 0.20 | 20.0% | 36.0% | 48.8% | 59.0% |
| 0.25 | 25.0% | 43.8% | 57.8% | 68.4% |
| 0.30 | 30.0% | 51.0% | 65.7% | 76.0% |

这是上界，不是承诺：重试不独立、场景会变乱、时间有限、重试成功率下降。但它说明**容错的边际收益可能大于单次精度**。

时间预算：

```math
k_{\max} = \left\lfloor \frac{180 - T_{\mathrm{setup}} - T_{\mathrm{safe}}}
{T_{\mathrm{attempt}} + T_{\mathrm{recover}}} \right\rfloor.
```

`T_safe` 建议 5–10s（回撤/让行余量）；`T_attempt` 用任务平均时长；`T_recover` 用 1–3s（重定位/backtrack）。长任务 `k_max` 小，不能盲目重试。

### 2.2 延迟预算

```math
T_{\mathrm{fb}} = \frac{H}{f_c} + \tau,
\qquad
\tau = T_{\mathrm{pre}} + T_{\mathrm{vlm}} + N_{\mathrm{dit}}T_{\mathrm{dit}} + T_{\mathrm{decode}} + T_{\mathrm{net}}.
```

| 场景 | H | f | τ | T_fb | 评价 |
|---|---:|---:|---:|---:|---|
| WLA 默认 | 30 | 30 | 50ms | 1050ms | 接触段基本开环 |
| CHUNK-SERVO | 5 | 30 | 50ms | 217ms | 可 1–2 次接触修正 |
| 高 RTT | 5 | 30 | 150ms | 317ms | 降增益/加 H |
| 低控制频率 | 5 | 10 | 50ms | 550ms | 改 H=3 或只做 PBVS |
| 量化 + 低 RTT | 5 | 30 | 20ms | 187ms | 需实测 |

量化节省：

```math
\Delta T = T_{\mathrm{BF16}} - T_{\mathrm{Q}}.
```

`ΔT` 的三个去向：

1. **多端口**：N 个机器人共享 GPU；吞吐 `N/T_total`。
2. **快速重规划**：故障后 150ms 级重规划，而不是 300ms。
3. **更短 chunk**：只有 p99 允许时才降到 3–5 步。

**不要**把 `ΔT` 花在更多去噪步数或更大模型上。

### 2.3 记忆的价值

事件记忆 `M_t = {e_i}`，每个事件包含时间、类型、物体 ID、位姿、关键帧、置信度。检索分数：

```math
s(e) = \mathrm{sim}_{\mathrm{vis}}(q,e)
+ \lambda_1 \mathrm{sim}_{\mathrm{pose}}(T_{\mathrm{target}},e.T)
+ \lambda_2 e^{-\Delta t/\tau_m}
+ \lambda_3 \mathbf{1}[\mathrm{phase}(e)=\mathrm{phase}(q)]
- \lambda_4 \mathrm{cost}(e).
```

保留 top-k（k≤8）；只有 `s(e) > θ_m` 才用于重定位/子目标；否则回退 VLA。

记忆的净价值：

```math
V_M = \Delta p_{\mathrm{success}} \cdot V_s
- \lambda_t \Delta T_{\mathrm{mem}}
- \lambda_c \mathrm{storage}.
```

如果 `V_M <= 0`，不要启用该事件；不是所有历史都值得记。

### 2.4 报警的干预价值

RESCUE 式：

```math
V(a) = P(R=1\mid a)\,E[\Delta p\mid R=1]\,V_s
- P(\mathrm{false}\mid a)\,C_f
- C_{\mathrm{delay}}.
```

只有 `V(a) > 0` 才干预。误报预算：

- backtrack：`P(false) <= 5%`；
- reset/salvage：`P(false) <= 2%`（RESCUE 的 2.0–3.3% 更保守）。

检测 AUROC 只用于排序候选检测器，不用于上线阈值；阈值用离线反事实分支选。

### 2.5 预算调度目标

```math
\max_{\pi}\; \mathbb{E}[1[\mathrm{success}]]
+ \lambda_s \mathbb{E}[\mathrm{step\_score}]
- \lambda_t \mathbb{E}[\mathrm{time}]
- \lambda_r \mathbb{E}[\mathrm{risk}],
```

约束：

```text
time <= 180s
chunk_size fixed at handshake
single model (no second policy)
per-port state isolation
no cross-episode online learning
```

由于排名先看成功率，`λ_s` 应小；只有当成功概率低于阈值且时间不足时才提高 salvage 权重。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port Runtime (CPU)             │
                    │  ├─ EM-RING (events + backtrack)    │
                    │  ├─ FT-LADDER (detect + recover)    │
                    │  ├─ BUDGET-ORCH (route + salvage)   │
                    │  ├─ CHUNK-SERVO (5-step servo)      │
                    │  └─ action adapter (WLA 54D → API)  │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared quantized WLA server (GPU)  │
                    │  VLM W8/W4 + DiT action head BF16   │
                    └─────────────────────────────────────┘
```

- 每端口一个 `Runtime` 实例：独立 `reset()`、独立事件环、独立预算、独立计划缓存。
- 共享 WLA server：一份权重，混合精度；session ID 区分端口；请求可批处理。
- GPU 12.46GB BF16 → W8 约 6–7GB → 一张 24GB 可服务 2–3 端口；W4-protected 约 4GB，可更多，但动作头仍占显存。
- CPU 线程不阻塞 websocket；VLA 请求异步；任何异常返回上一组合法 chunk 或安全 hold。

- `action_chunk_size` 是提交前选定的超参数；不要在运行时改。
- 图像 resize 是带宽/延迟的第一杠杆；先测 128/240 两档。

### 3.3 动作适配（WLA 54D → API 21D）

```text
WLA 54D:
  left_ee_rel[6], left_gripper[1], left_hand[6],
  right_ee_rel[6], right_gripper[1], right_hand[6],
  waist[3], torso[3], base_vxvy[2], base_wz[1],
  base_pose_rel[6], height[1], left_leg[6], right_leg[6]

挑战赛 ee 21D:
  left_ee_abs[6], right_ee_abs[6],
  left_gripper[1], right_gripper[1], pivot[7]
```

映射：

1. `left_ee_abs = compose(T_base_ee_left_current, exp(left_ee_rel))`；转 xyz+rpy。
2. `right_ee_abs` 同理。
3. gripper 直通（校验 0–1/量程方向）。
4. `pivot` 从 WLA base/waist 组合；先用 `example_env.py` 和单任务通道验证符号/顺序；不确定时返回全零 pivot，只验证双臂。
5. 腿部/灵巧手在 `ee` 模式不直接下发。

**关键细节**：WLA 的每个未来动作是「相对 plan-time 当前 EE」的位姿；adapter 必须先把整个 30 步 compose 成 base 系绝对目标，再按 chunk 切片。否则第 6–30 步以错误锚点解释，产生系统性偏移。

### 3.5 `get_action` 伪代码

```python
class RewindPolicy:
    def get_action(self, obs):
        self._tick(obs)                      # 更新事件环/backtrack buffer
        self._update_faults(obs)             # 确定性检测器
        self._update_budget(obs)             # 剩余时间/成功概率

        decision = self.orch.decide(self.state)
        if decision.kind == "hold":
            return self._safe_hold(obs)

        if decision.kind == "backtrack":
            a = self.backtrack.plan(self.state, obs)
            return self.adapter.to_api(a, obs, self.token)

        self._maybe_request_plan(obs)        # 异步 VLA
        a_ff = self._next_plan_chunk()
        if self.state.mode == "SERVO":
            delta = self.servo.compute(obs, self.goal)
            a_ff = compose_relative(a_ff, delta)
        return self.adapter.to_api(a_ff, obs, self.token)

    def reset(self):
        self.events.clear()
        self.attempts.clear()
        self.backtrack.clear()
        self.plan = None
        self.future = None
        self.state = INIT
        # route_memory is frozen, NOT cleared
```

`_maybe_request_plan`：

```python
def _maybe_request_plan(self, obs):
    if self.future is not None and not self.future.done():
        return
    if self.future is not None:
        self.plan = self.future.result()
        self.plan_age = 0
        self.future = None
    if self.plan is None or self.plan_age >= self.plan_ttl:
        snapshot = copy_obs(obs)
        self.future = self.executor.submit(self.vla.predict, snapshot)
```

规则：

- VLA 永远不阻塞 `get_action`（冷启动除外）；plan 过期用旧 plan + 伺服。
- 每个 chunk 只做一次伺服；伺服失败不影响返回合法动作。
- 异常 → 返回上一组合法 chunk 或安全 hold；绝不返回 NaN/错误形状。

### 3.6 `reset()` 语义

- 清空：事件环、backtrack buffer、失败计数、当前计划、当前 chunk、当前目标、当前子目标。
- 保留：route memory（冻结）、量化模型权重、演示索引（只读）。
- 不做跨 episode 在线学习；如果将来要做，必须单独评估合规性。

### 3.7 状态机

```text
INIT ──first obs──▶ PLAN ──plan ready──▶ EXECUTE
  ▲                   ▲                    │
  │                   │                    ├─ d_t < d_c ──▶ CONTACT
  │                   │                    │                 │
  │                   │                    │                 └─ release ──▶ EXECUTE
  │                   │                    │
  │                   └── replan ◀── RECOVER ◀── alarm/V>0

  └──────────────────────────────────────┘
任意状态 ──time low / irreversible──▶ SALVAGE / YIELD / SAFE_STOP
```

## 4. AQ-MP：动作头保护的混合精度

### 4.1 模块分组与保护

| 模块 | 默认精度 | 可量化 | 理由 |
|---|---|---|---|
| Qwen VLM | BF16 | W8A8 / W4A16 | 最大显存；语义特征可容忍低比特 |
| robot-state projector | BF16 | 否 | 小、对动作敏感 |
| DiT action head | BF16 | 否/仅 W8 | 动作精度命门 |
| 输出投影 / 最后 1–2 层 | BF16 | 否 | VLAQuantBench 证明保护一个输出投影即可救回 |
| cross-attention value/output | BF16 | 谨慎 W8 | 与动作条件强相关 |
| 图像预处理 | FP32/uint8 | — | 可能成为新瓶颈 |

### 4.2 分配算法

```text
输入：模块列表 L，显存预算 M，延迟预算 T，校准集 D
输出：每模块精度 p_l

1. 对每个 l，估计量化到候选精度后的 final-action error：
   e_l(p) = E_{(o,a)~D}[ || f_{p_l}(o) - f_BF16(o) ||_action ]
2. 估计 latency/memory：
   t_l(p), m_l(p)  (profile, not theoretical FLOPs)
3. 在 sum m_l <= M, sum t_l <= T 下，最小化 sum e_l(p)
   用贪心：每 MB 换 action error 最大的模块先降精度
4. 保护集合 P = {action head, output proj, state proj, last 1-2 layers}
5. 闭环验证：5 任务短 rollout；不通过则回退该模块
```

### 4.3 校准

- 数据：33k 演示，按 session/物体/背景分组；校准集不跨 split。
- chunk-aware：包含完整 chunk（含未执行 suffix）和去噪步分组；不要只用当前帧。
- 动作感知：用 final-action error，不用 weight MSE。
- 任务感知：QbD 式短闭环成功率可作为二次筛选；但必须真机复核（QbD 在 π0.5 真机翻车）。

### 4.4 服务与图审计

- 后端：TensorRT-LLM / ONNX Runtime / torchao / llm-compressor（按硬件选）。
- 必须用 graph inspector 确认低比特 kernel 真的存在；SmolVLA 的「INT8 实为 FP32 图」是反面教材。
- 监控：p50/p99、显存、batch、CPU 预处理占比；VLA-HWBench 提醒优化后 CPU 可能成新瓶颈。
- 多端口：连续 batching / 请求队列；每端口 session 隔离；batch 大小 2–4 起步，测 p99。

### 4.5 预期与失败模式

| 指标 | BF16 | W8 | W4-protected |
|---|---:|---:|---:|
| 权重显存 | 12.46GB | ~6–7GB | ~3–4GB + 动作头 |
| 加速比（p99） | 1.0× | 1.3–1.8× | 1.8–2.5× |
| 成功率 | 基线 | 目标 ≤1pp 降 | 目标 ≤2pp 降 |
| 端口/24GB | 1 | 2–3 | 3–5（受动作头/激活限制） |

失败模式：

- 动作头被量化 → 接触任务崩（VLAQuantBench 7.0% vs 70.5%）。
- 仿真选参 → 真机翻车（QbD π0.5）。
- 假量化 → 延迟降但成功率降，且无法解释（SmolVLA 图审计）。
- CPU 预处理成瓶颈 → 量化收益被吃掉（VLA-HWBench 12→39%）。
- 上下文宽度/图像 resize 改变 → 成功率变化被误归因于量化（SmolVLA 16/24/32）。

## 5. EM-RING：事件记忆与回退缓冲

### 5.1 事件类型与触发

| 事件 | 触发 | 存什么 | 用途 |
|---|---|---|---|
| `first_seen` | 目标首次进入 ROI | 位姿、关键帧、置信度 | 初始目标 |
| `grasp_close` | 夹爪命令闭合 | EE 位姿、物体位姿 | 抓取尝试 |
| `grasp_open` | 夹爪命令张开 | EE 位姿、物体位姿 | 放置/释放 |
| `lift` | 物体随夹爪上升 | 相对位姿 | 抓取成功证据 |
| `slip` | `r_grasp` 突变 | 位移、时间 | 滑移恢复 |
| `place` | 物体停止且夹爪张开 | 目标位姿 | 子目标完成 |
| `human_edit` | `edit_score` 高 | 场景变化、关键帧 | 让行/重定位 |
| `reobserve` | 重定位成功 | 新位姿 | 更新目标 |

### 5.2 事件选取与压缩

- 只在事件触发时存关键帧；128×128 JPEG（5–10KB）。
- 每类事件最多 4 条；总事件 ≤32；总内存 <1MB/端口。
- 物体 ID 用任务/阶段 + 颜色/几何描述子；不用人脸/身份。
- 关键帧只保留任务物体 ROI；不保留全图/人。

### 5.3 backtrack buffer

```text
W = 90 frames (3s @30Hz)
store: t, T_ee_meas, gripper, T_obj_est, action, r_track, vis_quality
```

回退点选择：

```math
b^* = \arg\max_{b \in [t-W, t-5]}
\left[
\mathbf{1}[\mathrm{obj\ visible}]_b
+ \mathbf{1}[\mathrm{no\ contact}]_b
+ \mathbf{1}[r_{\mathrm{track},b} < \theta]
- \lambda \cdot \mathrm{retrace\_time}(b)
\right].
```

回退执行：

- 逆序执行 EE 路径，低速度、限加速度。
- 每 5 步检查跟踪残差/视觉质量；异常则停止回退，转 L5/L6。
- 到达后保留事件/失败计数，清空局部计划；把控制交回 VLA。
- 最大回退 3s；超过则不再回退。

### 5.4 子目标图

从演示 + 任务描述离线构建：

```text
task -> [subgoal_0, subgoal_1, ..., subgoal_n]
subgoal -> {expected_duration, sensor_signature, recovery_primitives, step_score}
```

示例（HangCup）：approach → grasp → lift → align to rack → hang → release → verify。
示例（ZipUp）：approach zipper → grasp pull → pull segment → release → re-grasp → ... → verify。

用途：

- 进度监控：当前子目标、是否停滞。
- 记忆：已完成/未完成子目标。
- 检索：按 phase 选演示片段/目标图。
- salvage：选择安全子目标保步骤分。

### 5.5 route memory（冻结）

离线在单任务通道/仿真里测每个任务/阶段/策略的 `(success, time)`：

```text
route[(task, phase)] = [
  ("vla", 0.22, 12.0),
  ("servo", 0.28, 13.5),
  ("backtrack", 0.35, 15.0),
  ("retry", 0.30, 11.0),
]
```

运行时按预算选期望收益最高的策略；不更新。它是**超参数查找表**，不是第二个模型。

### 5.6 记忆参与决策的三种方式

1. **重定位**：`human_edit`/遮挡后，用最近事件位姿 + 当前腕部图局部匹配；成功则更新目标，失败则 L5。
2. **子目标条件**：把当前 phase/已完成子目标作为检索 key；如果 VLA 支持 prompt，可加入「已完成 X，现在做 Y」；否则用检索选择演示片段/目标图。
3. **失败去重**：同一物体、同一相对位姿、同一失败类型连续两次 → 禁止原样重试，升级到 backtrack/replan。

### 5.7 可选记忆适配器（C2）

如果 C1 的「记忆只做检索/状态机」不够，给 DiT action head 加 cross-attention：

```text
memory tokens: [event_pose, event_key_feat, time_embed, type_embed] x k
action head cross-attention: current obs tokens + memory tokens
train: freeze VLM, train DiT + memory adapter + state projector
```

规模 1–3M 参数（CogMemory 3.45M 可参考）；与 action head 联合训练，同一个 checkpoint。风险：单模型解释、训练数据/算力、过拟合；先做 C1，C2 只在 G-M1 失败时启用。

## 6. FT-LADDER：可恢复性感知的容错

### 6.1 故障分类

| 类型 | 信号 | 严重度 | 可逆 | 首选恢复 |
|---|---|---|---|---|
| 抓空 | 夹爪闭合但物体未随动；`r_grasp` 高 | 中 | 高 | L2 重定位 + L3 重抓 |
| 滑移 | 物体相对夹爪位移；`r_grasp` 突变 | 中 | 高 | L1 降速 + L3 重抓 |
| 卡住/碰撞 | `r_track` 大；关节速度异常 | 高 | 中 | L1 停 + L4 回退 |
| 目标丢失/遮挡 | 视差有效低/inlier 少/目标不在 ROI | 中 | 高 | L2 记忆重定位 |
| 人为移动 | `edit_score` 高 | 中 | 高 | L7 让行 + L2 重定位 |
| 子目标错/循环 | 进度停滞、chunk 不一致 | 中 | 中 | L5 重规划 |
| 延迟/超时 | p99 超预算、形状异常 | 高 | 高 | hold/上一 chunk |
| 不可逆风险 | 人进入、玻璃、液体、过载代理 | 高 | 低 | L7 安全停 |

### 6.2 检测器

```text
r_track   = || log(T_meas^{-1} T_cmd_prev) ||
r_grasp   = || T_obj_meas - T_ee_meas * T_obj_ee* ||
r_static  = || T_obj_meas(t) - T_obj_meas(t-Δ) ||
edit      = || T_obj_meas(t) - T_obj_pred(t) ||   # 静态/抓取都解释不了
chunk_dis = || a_new[0:H] - a_old[t:t+H] ||
stall     = t - last_progress_time
vis_bad   = disparity_valid < 0.7 or inliers < 15 or blur < θ
lat_bad   = p99_rtt > budget or timeout
```

阈值：

- 从成功演示的 95/99 分位校准；按任务/相位分别设。
- 连续 K 帧触发（K=3–5）以抑制噪声。
- 不使用力/触觉；`r_grasp`/`edit` 是视觉 + 几何代理，不是力估计。

### 6.3 报警门控

```python
def should_intervene(alarm, state):
    p_rec = state.recoverability[alarm.type]   # offline counterfactual
    p_false = state.false_alarm[alarm.type]
    gain = state.expected_gain[alarm.type]
    cost = state.intervention_cost[alarm.type]
    V = p_rec * gain - p_false * cost - state.delay_cost
    if alarm.type in ("reset", "salvage"):
        return V > 0 and p_false <= 0.02
    return V > 0 and p_false <= 0.05
```

`recoverability` 来自离线反事实：在失败 checkpoint 分别执行 continue / backtrack / retry / reset，统计最终成功；不是拍脑袋。

### 6.4 阶梯

| 级别 | 动作 | 触发 | 成本 | 失败后 |
|---|---|---|---|---|
| L0 | 继续 | 无报警 | 0 | — |
| L1 | 降速/降增益/低通 | 轻微跟踪差/接触 | 0.1–0.5s | L2 |
| L2 | 停 + 重定位 | 目标丢失/编辑 | 0.5–2s | L3 |
| L3 | 重抓/重放原语 | 抓空/滑移 | 1–3s | L4 |
| L4 | backtrack | 卡住/连续失败 | 1–3s | L5 |
| L5 | 重规划 | 子目标错/回退后 | 0.3–1s | L6 |
| L6 | salvage | 成功概率低/时间紧 | 1–5s | L7 |
| L7 | 让行/安全停 | 人/不可逆 | 0–1s | 结束 |

### 6.5 安全滤波

没有力/触觉，只做运动学 + 视觉代理：

- 关节限位/速度/加速度；
- 工作空间包围盒（桌面、机器人基座、相机视野）；
- 自碰撞胶囊（G1 URDF）；
- 桌面高度先验；
- CBF 式一阶约束：

```math
\dot h(x) + \alpha h(x) \ge 0,
```

把期望动作投影到安全集。`h` 可以是关节限位余量、工作空间边界距离、自碰撞距离。

- 人类让行：不声称识别人；用 `edit_score` + 工作空间运动/遮挡 + 安全边界触发停止。人进入 → L7。

### 6.6 预算策略

```python
def decide(state):
    B = 180 - state.elapsed - T_SAFE
    if B <= 0 or state.irreversible_risk:
        return SAFE_STOP
    if state.human_in_workspace:
        return YIELD
    if state.success_prob > THETA_S and B > state.time_to_finish:
        return CONTINUE
    if state.recoverable and state.alarm_value > 0 and B > state.recovery_time:
        return LADDER
    if state.step_score_gain > state.salvage_cost and B > state.salvage_time:
        return SALVAGE
    return SAFE_STOP
```

`success_prob` 用 route memory + 当前进度 + 失败次数估计；不是第二个模型。

### 6.7 人为干扰协议

- 检测：`edit_score` 高 + 场景运动无法用自身动作解释 + 目标位姿突变。
- 响应：先停/让行（L7），再重定位（L2）；目标仍可见 → 更新事件/目标；不可见 → 用最近事件位姿 + 头双目搜索；仍失败 → L5 重规划。
- 不识别人类身份；不记录人脸；只记录任务物体事件。
- 恢复后降低增益/速度，避免二次碰撞。

## 7. BUDGET-ORCH：180 秒的投资组合

### 7.1 任务预算表（先验）

|---|---|---|---|
| 短/高重试 | HangCup 6.2s、StackBowls 10.1s、DisconnectEthernet 10.5s、FruitSorting 10.7s、FruitCollection 10.8s、ColorArrangement 13.6s、PaperCupStacking 13.9s、ZipUp 14.1s | 8–20 | backtrack/retry |
| 中 | PlugCharger 15.1s、PackBag 15.1s、Syringe 15.3s、PickOutBattery 16.1s、PlugInEthernet 16.4s、ArrangeTestTubes 17.8s、PackDoll 19.6s、StoreCups 19.8s、OrganizePencilCase 20.5s、ArrangePlates 21.3s、PourOutMedicine 21.8s、OrganizeStationery 23.9s、StoreEarphones 24.1s、OrganizeTools 25s、FoldTowel 25.8s、PackPhone 29.2s、SpellRobot 31.2s | 4–8 | 记忆 + 一次做对 |

### 7.2 路线选择

```text
route[(task, phase)] -> best strategy under remaining budget
```

策略集合：`vla`、`servo`、`backtrack`、`retry`、`salvage`。选择规则：

```math
\mathrm{score}(s) = \hat p_s \cdot V_s
+ \lambda_q \hat q_s
- \lambda_t T_s
- \lambda_r R_s.
```

`\hat p_s` 来自 route memory + 当前进度；不是在线学习。

### 7.3 salvage

- 只在成功概率低于阈值且时间不足时启用。
- 选择安全、可验证的子目标（放回容器、归位、松手、退回安全区）。
- 不要为了步骤分放弃本可成功的重试；排名首先看成功率。
- 如果官方步骤分不可观测/不单调，salvage 只做“减少损坏/便于收尾”，不博弈分数。

### 7.4 竞赛组合

- 先做短/高重试任务 + 接触任务：HangCup、StackBowls、ZipUp、PlugInEthernet、DisconnectEthernet、PlugCharger。
- 再做人为干扰/记忆任务：所有任务的 human 轴（2/10）+ 长程（ToolboxStorage、StorePaddle、FoldTowel、SpellRobot）。
- 最后做背景/未见物品：VLA 数据增强 + 局部 ROI，不投纯几何伺服。
- 不把 19 个 A 档任务一次铺开；按 `q_t × Δ / cost` 排序，每测 3–5 个更新。

### 9.5 门汇总

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|

| G-Q1 | 量化快且不降点？ | 5 任务 ≤1–2pp 降；p99 加速 ≥1.5×；图审计 | 只 W8；保护更多层 |
| G-M0 | 记忆可检索？ | 重定位 ≤2cm/5°；top-5 ≥80% | 退回 API 稀疏堆叠 |
| G-M1 | 记忆涨点？ | 3/6 +5pp；短任务不回归 | 只保留离线 |
| G-F0 | 检测够早？ | AUROC ≥0.85；误报 ≤5%；≤200ms | 只保留高精度检测 |
| G-F1 | 干预值得？ | `V(a)>0`；3/5 +5pp；无碰撞上升 | 关闭 reset/salvage |
| G-B0 | 预算守得住？ | 180s 完成率 ≥95%；无超时 | 降 k_max |
| G-I0 | 32 任务稳定？ | 端口隔离、reset、内存、p99 | 回退基线 |
| G-Final | 比 CHUNK-SERVO 好？ | 32×10 +2–5pp；步骤分不降 | 只保留有效模块 |

### 9.6 统计

- 320 trials、`p≈0.25`：单次标准误约 `sqrt(0.25*0.75/320)=2.42pp`。
- 配对 A/B 的方差取决于任务内相关；报告配对差值 bootstrap 95% CI。
- 不用 +1–2pp 下结论；至少 3 个任务同方向 + 5 次配对。
- 数据泄漏：按 session/物体/背景分组；相邻帧不跨 split；不用评测图像训练。

## 10. 竞赛策略

### 10.1 任务分层

| 层 | 任务 | 主投 | 理由 |
|---|---|---|---|
| 短/高重试 | HangCup、StackBowls、DisconnectEthernet、FruitSorting、FruitCollection、ColorArrangement、PaperCupStacking、ZipUp | backtrack/retry | 180s 内 k 大；失败可恢复 |
| 接触/插入 | PlugInEthernet、PlugCharger、Unlock、ArrangeTestTubes、StackBowls、HangCup、ZipUp | servo + fault | 最后 3 厘米；接触检测 |
| 长程/记忆 | ToolboxStorage、StorePaddle、SpellRobot、PackPhone、FoldTowel、OrganizeStationery | 事件记忆 + 子目标 | 长程/多阶段；重试 ROI 低 |
| 泛化轴 | 所有任务的 human/背景/干扰物/未见物品 | 记忆重定位 + VLA 增强 | human 20% 权重；背景/干扰物靠局部 ROI |
| 观察/低投 | 单任务通道里 `p_t≈0` 且早期感知失败 | VLA 基线 | 不投伺服/容错工程 |

### 10.2 A/B 顺序

1. WLA + adapter + chunk 8 基线；单任务跑通 1 个任务。
2. 七阶段 profile；确定瓶颈。
3. W8 量化；5 任务闭环；图审计。
4. 事件记忆（C1）；重定位/长程 A/B。
5. FT-LADDER（检测 + backtrack + retry）；故障注入。
6. 预算调度 + salvage；180s 验证。
7. 32×10 干跑；正式提交。

### 10.3 提交节奏

- 若允许多次提交：先交安全基线锁「更早提交」tie-break；再交 REWIND。
- 若只允许一次：单任务通道打磨到 G-Q1/G-M1/G-F1 过门，再交。
- 不要把 320 trials 浪费在未验证的 A/B 上。

### 10.4 预期收益

| 来源 | 保守 | 乐观 | 备注 |
|---|---:|---:|---|
| AQ-MP | 0pp（使能） | +1–2pp | 主要通过多端口/快重规划/更短 chunk |
| EM-RING | +1–3pp | +3–6pp | 长程/遮挡/human；参照 WholeBodyMem 但打折 |
| FT-LADDER | +2–4pp | +4–7pp | Backtrack Long +7.4pp；本赛事更杂 |
| 组合 | **+2–5pp** | **+5–8pp** | 必须配对 A/B；可能被误报/时间吃掉 |

这些是设计目标，不是承诺；G-Q1/G-M1/G-F1 不过就不提交。

## 12. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定第二个模型 | C1 首选；C2 同 checkpoint 小模块并说明；不做 C3 |
| 量化降点 | 接触任务失败 | 动作头 BF16；闭环选参；W8 保底；图审计 |
| 量化不加速 | 瓶颈 CPU/网络 | G-Q0 先拆解；优化预处理/批处理 |
| 记忆带宽/token | p99 上升 | 事件稀疏；128×128；≤32 条；不堆全帧 |
| 检索 mismatch | 错误重定位 | 任务/相位过滤；top-k 重打分；置信度低回退 VLA |
| 误报/晚报 | 无谓回退/错过窗口 | `V(a)` 门控；反事实阈值；误报预算 |
| backtrack 碰撞 | 安全/损坏 | 低速度/限加速度/CBF/路径检查/最大 3s |
| 时间预算 | 重试拖垮长任务 | 每任务 k_max；剩余时间门控；salvage |
| 记忆泄漏/隐私 | 公平性/合规 | 只存任务物体；不存人脸；reset 清空；不上传 |
| 跨 episode 学习 | 规则/公平性 | 禁止；route memory 冻结 |
| 评测噪声 | 假阳性 | 配对 A/B；bootstrap；重复；不反推榜单 |
| 端口串扰 | 结果不可信 | 每端口独立；session ID；reset 测试 |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组；相邻帧不跨 split |
