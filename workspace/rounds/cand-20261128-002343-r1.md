## 1. 直觉与动机

**灵感 1（中间件 → 分数不只丢在模型里，也丢在模型与环境之间）**
直觉：同一份权重，换相机角色名、换归一化统计、晚一拍出 chunk、把相对动作当绝对动作，分数就会掉。F21/F22 说明官方自己就有一层复杂的 action/state 处理与槽位映射，而 adapter 已有「命名漂移」隐患。第 2 轮把 110 语料、增广、检索都当模型侧的活，忽略了策略真正面对的是**接口**。反直觉点：**泛化缺口里有一部分是「接口缺口」——它不需要再训练就能回收，但必须先被测量出来。** 所以本轮把中间件从部署胶水升级为「测量仪器 + 契约层」：用 metamorphic/一致性测试把总分损失分解成 模型项 / 接口项 / 时序项，给每项一个可回收上界。

**灵感 2（模型蒸馏 → 单模型不是约束，是蒸馏的目标）**
直觉：第 2 轮的 I3（关键点伺服）、I7（世界模型前瞻）、I9（reset 检索）都是「推理期变聪明」，却同时踩单模型边界（PR2）与延迟预算（P6）。蒸馏给统一出路：让这些组件在离线当教师，用它们的输出监督一个只吃部署观测的学生；部署时只有一个模型，聪明被摊销进权重。反直觉点：**任何测试时技巧，先问「能不能蒸馏掉」——能蒸馏，就同时消灭合规风险与延迟成本。** 蒸馏也适用于数据：把 110 语料蒸馏成紧凑「技能核心集」，比全量加权共训更抗负迁移。F20 还给出一个具体杠杆：官方动作头只用 4 步推理，F23 证明 4→1 步的自蒸馏在同类 flow-VLA 上可行。

**严谨定义**
- **中间件**：episode 级确定性变换层 M：(o_{t-h:t}, a_{t-h:t}, s_t) ↦ a_t^exec，满足四契约——(i) 接口封闭（只读声明字段）；(ii) episode 隔离（按 episode id 键控，reset() 清空）；(iii) 有界计算（无网络、无在线学习、延迟可测）；(iv) 语义可解释（每个变换有名、有开关、有 conformance 测试）。M 包含：观测规范化、动作空间适配、chunk 缓存/调度、延迟补偿、安全投影、干预检测、影子日志。
- **模型蒸馏**：教师 T(a|o,z)，z 为特权信息（未来帧、仿真态、检索命中、集成、额外算力）；学生 S_θ(a|o)。目标
  L = E_{o~d_S}[ D(T(·|o,z) ‖ S_θ(·|o)) ] + λ·L_task + μ·R(θ)，
  其中 d_S 必须是**学生自己诱导的状态分布**（on-policy，DAgger 式），否则协变量偏移会让离线增益在真机蒸发。三类：行为蒸馏（特权→可部署）、采样步蒸馏（4 步 flow→1–2 步）、数据蒸馏（大语料→核心集）。
- **摊销特权推断**：把训练期可得的特权线索当条件，训练学生从首帧/短历史直接预测该线索对应的行为，推理期不再需要该线索。I9 检索、I3 伺服、I7 前瞻都可被摊销。

**统一**：中间件回答「在哪里收集教师标签、部署时如何守住接口」；蒸馏回答「如何把教师能力压进一个合规学生」。合起来是一条流水线：**教师系统（数据引擎 + 检索 + 伺服 + 世界模型 + 集成）→ 中间件影子日志收集 on-policy 状态 → 三类蒸馏 → 单一学生 → 中间件运行期兜底。** 第 2 轮说胜负手在数据引擎；本轮补一句：**数据引擎的产出要通过蒸馏才能变成合规的部署能力。**

## 2. 对第 2 轮痛点的增量修订

- 新增 P9（接口/时序缺口）：损失可分解为模型项、接口项、时序项；接口项可离线测量、零训练回收。
- 新增 P10（单模型 vs 测试时技巧的张力）：I3/I9 的合规风险、I7 的延迟风险，可用特权蒸馏统一消解。
- P6（延迟）修正：F24 后，1 秒 chunk 缓存使延迟主要取决于重规划频率；I13 从「救命」降为「可选杠杆」，与量化做帕累托。
- P8（示教质量）补充：数据蒸馏比「全量 + 质量加权」更直接地降低负迁移与磁盘。
- P7（先手）补充：蒸馏管线是复利资产——教师可随轮次升级，学生只需重蒸。
- P1/P2 保留。

## 3. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

- **Q9（接口损失分解）**：如何用语义不变变换（相机角色重映射、已知内参缩放、动作单位缩放、界内时间抖动、相对/绝对动作语义交换）做 metamorphic 测试，把总分损失分解为模型/接口/时序三项并给出可回收上界？
- **Q10（特权可迁移性）**：教师依赖未来帧/仿真/检索/集成时，哪些行为是「部署观测可推断」的？如何用「特权信息差」与「可推断性探针」筛选蒸馏目标，避免学生只学到相关性？
- **Q11（三类蒸馏的叠加与冲突）**：行为、采样步、数据三类蒸馏同时做时，容量、分布、模式坍缩如何相互作用？在稀缺真机预算下如何用 L0 消融排序与止损？

## 4. 设计原则（新增 PR6/PR7）

- **PR6 推理期技巧蒸馏优先律**：任何提升分数的推理期模块，先评估「能否蒸馏进学生」；能蒸馏则不长期驻留推理路径。PR2 管「是否单模型」，PR6 管「如何把多组件压成单模型」。
- **PR7 中间件透明律**：中间件只做声明式、可复现、episode 隔离的变换；任何改变动作分布的变换必须有 conformance 测试与 A/B，禁止用「魔法后处理」掩盖模型缺陷。
- PR1–PR5 保留。

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2）

> 检索日期：2026-11-26（第 1 轮）、2026-11-27（第 2 轮）、2026-11-28（本轮）；来源见 §5。承接 v1.1：新增 I10–I13；I7 降级为蒸馏教师；I3/I9 增加「蒸馏出口」。清单只增改不重置。本轮新增 F20–F25；V1–V4 为待书面确认的规则边界，未确认前 I10/I11/I13 离线先行、不上计分通道。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I1 v3 考纲校准五轴增广引擎 ★★★★★
- **动机/差异**：同 v2（考纲卡、剂量-响应、轴间析因），把「零样本」转成「分布内」。
- **本轮增量**：增广器同时充当 **I10 的接口扰动源**（同一套轴变换用于模型鲁棒性与接口缺口测量）与 **I11 教师的难例源**，避免维护两套工具。
- **技术可行性/资源**：同 v2；1×24GB GPU，考纲卡 32×10 分钟。
- **落地步骤**：①考纲卡；②背景/干扰物放量；③外观/位置 L0；④剂量定档；⑤轴间析因；⑥接入 I10/I11 的数据接口。
- **风险**：同 v2；新增「增广变换与部署侧变换混淆」——二者必须用独立开关与独立随机种子，禁止共用。

### I2 v3 数据引擎 2.0：110 语料孪生迁移 + 加权共训 ★★★★★
- **动机/差异**：同 v2 三件事（孪生入训、loader 加权 patch、示教质量加权）。
- **本轮增量**：增加 **I12 数据蒸馏分支**——先用技能核心集做低成本共训，再决定是否放量到全量加权；两分支用 L0 对比，直接对撞第 2 轮最大风险（负迁移/体量淹没）。
- **技术可行性/资源**：高；核心集阶段可流式抽特征，不必先下载全量；训练 1×24GB 起。
- **落地步骤**：①孪生表；②loader patch + batch 频率单测；③核心集 vs 全量加权 L0；④正迁移才放量；⑤族级止损。
- **风险**：同 v2 负迁移；新增「核心集丢长尾」——按任务族分层配额 + 接触段保底。

### I3 v2 接触任务族关键点视觉伺服 ★★★★
- **本轮变化**：推理期伺服退居**教师/降级预案**；主链改为把伺服产生的接触段动作作为特权标签，蒸馏进学生（I11）。即使 V1/V2 收紧，主链仍是单模型。
- **落地**：伺服触发滞回 + 低置信回退（同 v1）；离线标注接触段 → 可推断性筛选 → 蒸馏；**I3' 降级预案**：若混合推理违规，改为训练时辅助监督（伺服关键点作辅助标签，推理纯端到端）。
- **风险**：伺服标签噪声与触发误判；蒸馏后学生只模仿「伺服成功段」——需负样本与置信门控。

### I4 v2 人手干预感知门控 + 自适应 chunk ★★★★
- **本轮变化**：并入 **I10 中间件**的一个模块；检测器与状态机不变（手部检测 + `obs_delta_indices` 历史栈 <50ms；INTERFERED→停持→重估→续做）。
- **增量**：干预检测同时写「影子日志」标记，供 I11 只在非干预段蒸馏、干预段排除；干预态短 chunk（4–6 步）/稳定态长 chunk（8–16 步）作为 I10 调度器策略。
- **风险**：误检导致停持丢分；用双阈值滞回 + 标称段不触发回归测试。

### I5 v3 非标称示教合成 + 得分点对齐恢复 ★★★★
- **动机/差异**：同 v2 四种合成（扰动重放/跨段缝合/世界模型生成/得分点过滤）。
- **本轮增量**：合成数据同时训练学生与 **I11 教师**（教师可看未来与仿真，学生只看部署观测）；用「可推断性探针」筛掉只有教师能用的恢复段，避免学生学不会的标签。
- **落地**：得分点逆向 → 3 弱任务试点（PlugCharger/ZipUp/PourOutMedicine）→ 进度头改得分点监督 → LoRA 增量 → 单任务通道 A/B。
- **风险**：同 v2；新增「合成-蒸馏双重误差放大」——先小规模真机 A/B 再放量。

### I6 v2 确定性低延迟部署服务 ★★★★★（↑）
- **动机**：P6/P9；官方 model_server 可直接改造（F12/F22）。
- **本轮变化**：显式定义**中间件契约**（I10）；延迟预算拆成「模型前向 + 采样步 + 中间件」三段。F20/F24 修正：官方 30Hz/horizon30，1 秒 chunk 可缓存，模型前向摊销为每 30 步一次；p99 目标按评测控制频率与重规划频率定（V3），而非沿用 WMA-0 的 15Hz/66ms。
- **落地**：共享 backend + 端口隔离 + fp8/INT8 + CUDA Graph + obs 预取 + 断线重连 + 健康探针（PR4）；chunk 缓存/调度交给 I10。
- **风险**：缓存陈旧观测导致闭环退化——按重规划频率设上限（如每 8–15 步强制刷新）；中间件状态泄漏——episode 隔离测试。

### I7 v2 世界模型 → 特权教师（降级）★
- **本轮变化**：正式裁撤推理期前瞻（兑现第 2 轮修剪判据），资产转 I11：WMA-0 仿真模式生成/续写「未来帧 + 反事实动作结果」，仅离线当教师特权信息。
- **风险**：世界模型误差污染教师标签；只在其置信区间内使用，并与真实示教做一致性抽检。**裁撤不等于废弃。**

### I8 v3 评测运营闭环 + 分级消融注册表 ★★★★
- **动机/差异**：同 v2 的 L0/L1/L2 与离线-在线相关性注册表。
- **本轮增量**：新增三类蒸馏消融（特权开关、蒸馏损失、核心集比例）与中间件 conformance 回归；注册表增加「接口项/模型项」分栏，检验代理指标是否只对某一项有效。
- **落地**：代理指标 → 注册表 schema → 首个用例 = I10 接口回收 + I2 孪生迁移 → 月度复盘相关性。
- **风险**：同 v2（相关性建立慢）；新增「中间件收益被误记到模型」——用裸模型 vs +M 的配对实验隔离。

### I9 v2 reset 期检索类比迁移 ★★★★
- **本轮变化**：推理期检索保留为可选软先验；主链改为**摊销检索蒸馏**——训练期用检索结果作特权条件，学生从首帧预测「该检索先验对应的动作参数」，部署时零检索、零额外开销。
- **落地**：物体-技能库 → 嵌入/索引 → 先验参数化 → 教师条件化 → 学生摊销 → 未见轴 L0 + 真机抽测。
- **风险**：同 v2 误检索；新增「摊销后先验不可解释」——保留阈值门控的轻量版作为可关闭兜底；V1/V2 书面确认。

### I10 中间件契约与接口损失分解（新）★★★★★
- **动机**：P9；分数不只丢在模型。F21/F22 证明官方接口层本身复杂且有槽位漂移风险。
- **与现有方案差异**：别人把中间件当胶水；本点把它当「测量仪器 + 契约层」，先量化再优化，且用 chunk 缓存把前向摊销。
- **技术可行性**：高，纯工程 + 离线评测；无需真机。
- **所需资源**：1 人周 + 本地 stub。
- **落地步骤**：①定义四契约与变换清单（观测规范化/动作适配/chunk 调度/延迟补偿/安全投影/干预检测/影子日志）；②metamorphic 测试套件；③在现有 checkpoint 上测「裸模型 vs +M」；④输出接口损失分解报告；⑤把回收项固化进提交模板。
- **风险**：测试覆盖不到真实故障模式——用真机日志回放补用例；chunk 缓存与评测语义冲突（V3）——保留逐步重规划模式。

### I11 特权信息摊销蒸馏（新）★★★★★
- **动机**：P10；I3/I7/I9 的合规与延迟风险；单模型是目标不是约束。
- **与现有方案差异**：不是把多组件塞进推理，而是把多组件变成离线教师，再蒸馏成一个只吃部署观测的学生。
- **技术可行性**：中-高；教师可先用现有组件拼装；学生沿用官方 frozen-VLM + DiT action head（F11/F25），可只训 action head/LoRA。
- **所需资源**：教师离线推理 1–2 GPU 日/轮；学生蒸馏 1×24GB 起（官方默认量级，F20/F25）；**部署零新增算力**。
- **落地步骤**：①教师清单与特权集定义（检索/伺服/前瞻/集成/未来帧）；②on-policy 学生 rollout + 教师标注（DAgger 式）；③可推断性探针筛样本；④三类损失（动作/特征/偏好）小规模对比；⑤L0 + 单任务通道 A/B；⑥确认 V2 后上主链。
- **风险**：特权信息差（见想法区 §6）；教师误差被学生继承；模式坍缩——分别用可推断性筛选、置信过滤、保留多模态学生（flow 头本身多模态）缓解。

### I12 示教数据蒸馏：110 语料 → 技能核心集（新）★★★★
- **动机**：P8 + 第 2 轮最大风险（负迁移/体量淹没）。
- **与现有方案差异**：v2 用「全量 + 加权」；本点先把语料蒸馏成紧凑核心集，再决定是否放量。
- **技术可行性**：高；技能段嵌入 + k-center/子模覆盖是成熟工具。
- **所需资源**：嵌入 1 GPU 日；流式抽特征，无需先下载全量。
- **落地步骤**：①技能段嵌入（动作+视觉+指令）；②k-center/子模覆盖选核心集；③质量加权；④L0 对比「核心集 vs 全量加权」；⑤正迁移才放量。
- **风险**：核心集丢长尾/接触细节——按任务族分层配额 + 接触段保底；嵌入不敏感——动作与视觉特征拼接。

### I13 动作采样步蒸馏（新）★★★
- **动机**：P6；官方 4 步 flow 推理（F20），F23 证明同类 flow-VLA 可 10→1 步自蒸馏。
- **与现有方案差异**：量化/编译是「同等步数更快」，本点是「更少步数」；二者可叠加做帕累托。
- **技术可行性**：中；需确认 V3 与官方采样器是否暴露步数配置。
- **所需资源**：1×24GB；离线蒸馏，部署零额外成本。
- **落地步骤**：①测 4 步的质量-步数曲线；②一致性/Reflow 式 1–2 步学生；③动作分布与成功率 L0；④p99 与动作健康度门禁；⑤真机 A/B。
- **风险**：少步化损失多模态细节——保留 2–4 步、按任务族选择；chunk 缓存已使延迟非瓶颈时，本项降为可选。

### 1.1 中间件契约 + chunk 缓存（I10）

```python
class PolicyMiddleware:
    """episode-scoped / deterministic / no network / no online learning."""
    def reset(self, episode_id):
        self.ep = EpisodeState(id=episode_id)      # 隔离；reset 清空
        self.cache, self.cursor = None, 0

    def canonicalize(self, obs):                   # F21：相机角色/尺寸/归一化
        obs = remap_camera_roles(obs, self.schema) # head_left / cam_wrist_left / cam_wrist_right
        return normalize_obs(obs, self.stats)

    def step(self, obs, policy):
        o = self.canonicalize(obs)
        if self.cache is None or self.cursor >= len(self.cache):
            self.cache = policy.propose_chunk(o)   # 30 步 ≈ 1s（F20）；每 30 步一次前向
            self.cursor = 0
        a = self.cache[self.cursor]; self.cursor += 1
        a = safety_project(a, self.limits)         # 界内/限速/平滑
        self.ep.shadow_log(o, a, self.cache)       # 供 I11 蒸馏
        return a
```

def interface_report(policy, M, eps):
    R_model = rollout(policy, eps)                          # 裸模型
    R_full  = rollout(lambda o: M.step(o, policy), eps)     # 模型 + 中间件
    return {
      "recoverable": R_full - R_model,                      # 中间件直接回收
      "brittleness": {k: action_divergence(policy, f) for k, f in INVARIANTS.items()},

### 1.3 特权摊销蒸馏（I11）

```python
def amortized_distill(student, teachers, env, probe, K):
    for _ in range(K):
        obs, done = env.reset(), False
        while not done:
            o = obs.deployable                       # 学生只看部署观测
            a_s = student.sample(o)                  # on-policy 学生动作
            z = {name: t.privileged(o) for name, t in teachers.items()}
            a_t = teachers["ensemble"].act(o, z)     # 可多步/多视角/未来帧
            w = probe.inferable(o, z)                # 0..1：该行为能否由 o 推断
            if w > TAU:
                update(student, w * (action_loss(a_s, a_t) + feat_loss(student, o, z)))
            obs, done = env.step(a_s)                # 用学生动作推进（DAgger）
```

## 2. 实验设计（分级消融协议 v3）

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0-M | 中间件一致性：裸模型 vs +M；语义不变变换脆弱性矩阵 | 离线（免费） | 标称不降；可回收 >0；相对/绝对语义交换显著恶化 |
| L0-D | 特权蒸馏：教师特权开关（未来/仿真/检索/伺服/集成）逐项消融 + 可推断性探针 AUC | 离线 | 学生保住教师增益 ≥50%（暂定）；特权差大的项收益应下降 |
| L0-C | 数据蒸馏：核心集 5/10/20/100% vs 全量加权 | 离线 | ≤20% 数据保住 ≥80% 全量增益 |
| L0-S | 采样步：1/2/4/8 步，成功率-p99 帕累托 | 离线 | ≤2 步且成功率降 <2%（chunk 缓存后本项可为可选） |
| L1 | 2^(k-p)：中间件变换 × 蒸馏目标 部分析因 | 离线 + 少量真机 | 主效应显著的 ≤3 组合进入 L2 |
| L2 | top 组合真机确认：≥2 任务 × 各 2 次/任务 | 单任务通道 | 真机增益 ≥ 离线预测的 50% |
| 门禁 | PR4 + 中间件 conformance 回归 | 本地 stub | 0 拒绝动作；p99 达标；episode 隔离无泄漏 |

**首批 L2 排队计划**：①I10 接口回收（最便宜、零训练）→ ②I11 蒸馏 I9 检索（合规价值最高）→ ③I12 核心集 vs 全量共训 → ④I13 采样步（若 V3 允许）。
