# 第 13 轮（新灵感循环第 4 轮；本轮灵感：「角色一致性」×「消融实验」）

> **基线**：第 12 轮 MetricVoiceGauge-NCD-HUT（定义 571–582；引理 104–112；实验 E607–E626）。
> 本轮纪律：**角色一致性证书 + 消融必要性证书 + 角色反事实探针**。不推倒 v12：HAS/HCC/HATD/HDT、v11 的 USG/TGC/BAA/GAGP/UC、v10 的 NGE/DSL/CC/CWM/CAE/NCP、v9 的 AC/MW/ID、v8 的 DA/SPR/Cal 与九不变式全部保留。三个新组件——RCG（角色一致性治理器）、ANC（消融必要性认证器）、RCP（角色反事实探针）——一律以**中立元**接入，失效即严格退回 v12（引理 118），再沿 v12 退化链退回 v11/v10/v9/v8/v7/v6。本轮只做三件事：把"谁在扮演什么角色"变成可证的一致性约束、把"消融"从论文末尾的配角变成预注册的因果证据协议、把"角色"与"消融"合流为角色反事实检验。

## 0. 直觉与动机

**灵感 1（角色一致性 → 角色义务、权限与证书的三方对齐）**
直觉：v12 已经能生成类型化的通用技能、给出迁移间隙证书、做双向锚定，但它始终默认**只有一个执行者、一套职责**。一旦系统进入人机协作、多机协同、或"同一机器人分时扮演搬运工/装配工/看护者"的场景，"角色"就成了隐形的安全边界：某个技能被赋予了超出其证书的能力（越权），某个模块承担了它并未被校准的职责（越责），两个并发角色争用同一物体或同一工作空间却各自以为安全（越界），交接时刻双方都以为对方已接手（空窗）。这些都不是单一技能证书能发现的——**证书是按技能发的，风险却常常按角色出现**。核心创新：**角色一致性证书（Role Consistency Certificate, RCC）**：把角色定义为带义务、权限、观测域、资源需求、时序契约与所需能力证书的**类型化对象**；RCC 要求"角色声明—执行效果—能力证书—物理资源—时序契约"五方对齐，任何对齐缺口都被显式记录为一致性余量或违规集，而不是被平均掉。

**灵感 2（消融实验 → 从"事后剪枝"到"预注册必要性证书"）**
直觉：v12 的消融（E625/E626）仍是**事后、单因子、以性能差为主**的检查：去掉 TGC 看失败率是否上升。这在工程叙述上够用，在因果上远远不够——单因子消融在模块强交互时会严重有偏（去掉 TGC 后 BAA 的锚点分布也变了），事后选择消融对象会引入多重比较与"叙事拟合"，而"去掉某模块性能下降"也不等于"该模块承担了不可替代的职责"。核心创新：**消融必要性认证器（Ablation Necessity Certifier, ANC）**：消融必须先**预注册**（假设、单元、设计、指标、停止规则、分析计划），采用**交互感知的因子设计**（而不是单因子顺序剪枝），并用**必要性证书 NC** 给出该单元边际贡献的置信下界；没有 NC 或 NC 不显著的可选单元只能被中立化，**安全关键单元被列入受保护集，永不可被消融移除**。消融不再是论文的补丁，而是模块保留与否的**证据门**。

**灵感 3（角色×消融 → 角色反事实与"预测—实测"一致性）**
直觉：角色一致性若只做静态检查，就永远发现不了"角色边界写对了、实际执行却串了"的漂移；而消融若只按模块做，就永远回答不了"这个角色到底是不是必要的，还是可以被另一个角色替代"。两者合流恰好互补：把**角色当作消融单元**，做 `do(ρ off)` 或 `do(ρ→ρ')` 的角色反事实，比较**证书模型预测的行为变化**与**影子模式实测的行为变化**。若二者一致且方向正确，角色一致性获得因果支持；若实测变化远小于预测，说明该角色是冗余的（角色重叠）；若实测变化远大于预测或出现在未声明维度，说明存在**角色泄漏（role leak）**——职责从声明边界溢出。核心创新：**角色反事实一致性（Role-Counterfactual Consistency, RCCf）** 与**角色消融安全包络**：反事实只在影子/低速/证书等价配置下进行，只用于发现问题与修订角色边界，**绝不用于放宽任何真实证书阈值**。

**三者如何统一**
统一为**角色义务—消融证据—反事实校正**的闭环：RCG 在每个决策周期检查角色赋值 ρ_t 与 v12 全部证书的一致性，输出 RCC 与违规/余量；ANC 在离线/低频预算内对"模块角色"与"功能角色"做预注册、交互感知的消融，输出 NC 并据此保留或中立化**非安全**可选单元；RCP 在安全包络内执行角色反事实，用 `do(ρ off)`/`do(ρ→ρ')` 的预测—实测差检验 RCC，并把不一致回写为角色边界修正建议或降级信号；RAC 只做排序、预算与调度。共享状态 `ζ_ra=(ρ_t, RCC, G_abl, NC, B_abl, history)`（当前角色赋值、一致性证书、消融图、必要性证书、消融预算、历史）。**RCG 回答"现在这套角色能不能安全成立"，ANC 回答"哪些角色/模块真的不可替代"，RCP 回答"角色边界是否如我们所信"。**

## 1. 研究问题（轮次升级版）

- **Q1（角色的可证边界）**：如何定义角色才既足够表达人机/多机协作，又能被证书逐项检验？"角色—技能—资源—时序"五方一致性在何种条件下可组合？当多个角色共享物体/工作空间/带宽时，联合证书如何构造而不退化为逐角色检查的简单合取？
- **Q2（消融的因果可辨识性）**：在模块强交互、角色可替代、样本预算有限时，单因子消融的偏差有多大？何种因子设计（分辨率、重复、分层）能在给定预算下辨识出必要性而不被交互项吞没？必要性证书如何做多重比较控制与预注册不可篡改？
- **Q3（角色反事实的检验力）**：在安全包络约束下，角色移除/替换能激发的行为变化是否足以检出真实的角色泄漏？预测—实测差的检验功效如何随角色耦合度、影子模式保真度与样本数变化？如何区分"角色冗余"与"角色泄漏"？
- **Q4（与 v12 的兼容与活性）**：RCC 的静态检查会不会把可行角色集清空？ANC 会不会误删有用模块或（更糟）试图移除安全模块？RCP 的影子实验会不会污染真实执行、拖垮 50Hz/p99≤22ms？新增模块能否守住预算并严格退回 v12？

## 2. 设计原则（在 P19–P21 基础上新增 P22–P24）

**P22 角色即受证义务律（Role as Certified Obligation）**
任何角色必须携带 RCC：义务/权限/观测域/资源/时序/所需能力证书六元组，且必须与 v12 的物理/接触/谐波/规范/gap 证书**逐项对齐**。执行效果超出声明义务、调用技能超出权限、资源占用超出声明、或交接前置不满足，均视为角色不一致；不一致只能触发拒绝、改派、降级或 `a_ask`，不得以"任务需要"为由临时扩权。

**P23 消融即预注册证据律（Ablation as Pre-registered Evidence）**
消融必须在观测数据前固定协议（假设、单元、设计、指标、停止与分析计划）；默认采用交互感知的因子/序贯设计而非事后单因子剪枝；任何"某模块必要"的结论必须由 NC 的置信下界支持，并做族错误率控制。**受保护集（安全/证书关键单元）不可作为消融单元**；ANC 只能中立化非安全可选单元。

**P24 角色反事实非放宽律（Role-Counterfactual, No Relaxation）**
RCP 只在影子模式、低速微扰或证书等价配置下运行，其轨迹必须通过 v12 全部适用证书，且不得进入主执行路径、不得改变任何真实阈值。预测—实测不一致只能导致**收紧**角色边界、追加验证或降级到 v12，绝不能解释为"证书可以放宽"。RCP 的失败本身是一等信号，不得被静默忽略。

## 3. 与基线的接口（如何退化）

- RCG 失效 ⇒ 注入角色中立元：全系统退化为单一 `role=executor`，其义务/权限恰为 v12 全部模块与 GAGP 的既有能力，**等价 v12 单执行者路径**；
- ANC 失效 ⇒ 注入消融中立元：保留 v12 全部模块，不做必要性门控、不做任何中立化，**等价 v12 模块集**；
- RCP 失效 ⇒ 注入反事实中立元：只保留静态 RCC，不执行任何 `do(ρ off)`/`do(ρ→ρ')`，**等价 v12 + 静态角色检查**；
- RAC 失效 ⇒ 由 v12 GAGP/NCP 直接选择角色与技能，消融仅作为事后审计，**等价 v12 决策路径**；
- 四者全失效 ⇒ MetricVoiceGauge-NCD-HUT v12，再沿 v12 退化链退回 v11/v10/v9/v8/v7/v6；
- **安全继承**：RCG 只能约束/过滤角色赋值，ANC 只能中立化非安全可选单元，RCP 只能影子运行并发信号，RAC 只能排序调度。任何新模块都不能放宽 v12 的 USG/TGC/BAA 与 v11 及更早的全部适用证书；四重/五重证书合取仍由 v12 原语检查（引理 117 升级引理 109）。

## 4. 预期贡献

1. **可证的角色一致性**：把"角色"从口语约定改写为带义务/权限/观测/资源/时序/能力证书的类型化对象，给出 RCC 与角色漂移的形式定义，覆盖 v12 完全未定义的"多角色、越权、交接空窗"风险面；
2. **消融的方法论升级**：把消融从论文末尾的事后检查升级为预注册、交互感知、带必要性证书与多重比较控制的因果证据协议，使"模块保留/中立化"本身成为可审计的决策；
3. **角色反事实一致性**：用 `do(ρ off)`/`do(ρ→ρ')` 的预测—实测差同时检验角色边界与消融结论，提出区分"角色冗余"与"角色泄漏"的判据，并给出安全包络；
4. **角色—消融—安全统一闭环**：E627–E646 覆盖角色一致性、越权/交接、消融偏差、因子效率、必要性证书校准、角色反事实、耦合、长跑，以及对本轮三组件自身的完整消融。

## 5. 本轮最大风险

**一句话**：角色边界与消融模型都由同一套有限团队/任务分布拟合而来，RCP 又用这套模型生成"预测"，于是角色定义的系统性错误可能**自洽地通过**反事实检验（预测与实测同错），而交互感知消融仍可能被"角色可替代性"混淆，最终在"角色一致、消融显著"的双重表象下，于未见过的新角色组合上发生越权或交接空窗——即**证据齐全的角色边界失败**。

**定义 583（类型化角色 Typed Role）** 角色是六元组
```
ρ = ( resp, auth, obs, res, temp, cap )
```
其中 resp 为可承诺的目标/义务集合（含退出条件），auth 为可调用的技能与证书范围，obs 为允许的观测/状态访问域，res 为所需物理与计算资源（物体、工作空间、带宽、算力），temp 为时序契约（截止期、前后序、同步点、WCET 分配），cap 为所需能力证书集合（v12 的物理/接触/谐波/规范/gap/中止点证书）。角色是**类型**，`ρ_t(a)` 是执行体/模块 a 在某时刻的**角色赋值**。

**定义 584（角色赋值与角色图 Role Assignment & Role Graph）** 角色赋值为映射 `ρ_t: A∪M → Role`，角色图为
```
G_ρ = ( V_ρ, E_pre, E_hand, E_res )
```
其中 V_ρ 为当前活跃角色，E_pre 为前后序约束，E_hand 为交接边（带交接前置/后置谓词），E_res 为共享物体/工作空间/带宽的资源冲突边。并发的角色集合必须满足：E_pre 无环，E_hand 端点谓词可满足，E_res 上的资源占用可被联合证书覆盖（定义 585）。

**定义 585（角色一致性证书 Role Consistency Certificate）** 对角色赋值 ρ_t，RCC 为
```
RCC(ρ_t) = ( ok, m, V, cov ),   ok ⇔ V=∅
```
它逐项检查六类一致性：
1. **能力**：`cap(ρ_t(a)) ⊆ ValidCerts(a)`，且被调用技能的绑定 β 落在 v12 UC 支撑集内；
2. **权限**：ρ 调用的每个技能与组合属于 `auth(ρ)`，且 `effect` 签名被 ρ 的 resp 覆盖；任何未声明副作用即违规；
3. **资源**：并发角色在 E_res 上的资源占用互斥，或存在联合证书 `Ĉ_joint` 同时覆盖接触/谐波/规范，且非简单逐角色合取；
4. **时序**：E_pre 无环、截止期与 WCET 在 EDF 下可行、同步点不产生死锁；
5. **交接**：对每条交接边，`post(ρ_i) ⇒ pre(ρ_j)` 在允许扰动下成立，且交接窗口内不存在双方都不负责的"空窗"；
6. **效果**：声明效果签名 `effect(ρ)` 在实际执行中以余量 m 覆盖观测效果（见定义 586）。
`m` 为最紧一项的归一化余量，`V` 为违规项集合，`cov` 为该 RCC 所用校准的覆盖。RCC 只读、只过滤，不生成技能、不放宽任何证书。

**定义 586（角色漂移 Role Drift）** 设声明效果维度为 D，观测效果为 `e_obs`，声明上界为 `e_dec`，则
```
d_t = max_{k∈D} max(0, (e_obs,k − e_dec,k) / s_k)     （s_k 为归一化尺度）
```
`d_t>0` 即发生角色漂移；漂移事件记为 `(t, ρ, k, d_t)`。漂移不是噪声：它意味着角色边界声明与实际执行不符，必须触发定义 585 的违规或定义 590 的反事实复核。

**定义 587（消融单元、消融图与受保护集 Ablation Unit / Graph / Protected Set）** 消融单元 u∈U 可为：模块（USG/TGC/BAA/GAGP/RCG/…）、功能角色（由 RCG 的角色类型定义）、接口（四端口）、证书（某一类过滤条件）。消融操作为
```
ablate(u, op),  op ∈ {neutralize, replace, freeze, mock}
```
消融图 G_abl=(U,E_abl) 记录单元与预期影响边（含预期交互）。**受保护集** `P_prot` 包含全部安全/证书关键单元——v11/v12 的物理/接触/谐波/规范/gap 证书、守卫、中止点、四端口的安全继承逻辑；`P_prot` 中的单元**不可作为消融移除对象**，只能作为只读观测对象。ANC 的任何输出都不能使 `P_prot` 中的单元失效。

**定义 588（预注册消融协议 Pre-registered Ablation Protocol）** 协议为
```
P_abl = ( H, U, D, M, N, R, S, A )
```
分别为假设、单元集、设计（单因子/因子/序贯）、指标与方向、样本与预算、随机化/分层、停止规则、分析计划。协议必须在采集消融数据**之前**固定，并以 `hash(P_abl)` 对锚定存档；数据后修改协议视为协议违规，对应 NC 作废。默认设计为**交互感知的因子/序贯设计**，而非事后单因子顺序剪枝。

**定义 589（必要性证书 Necessity Certificate）** 对单元 u，记
```
Δ_u = E[ J(full) − J(full \ u) ]     （J 为预注册主指标，越大越好）
```
在协议 P_abl 下得到估计 `Δ̂_u`、单侧置信下界 `L_u`、经多重比较校正的 p 值 `p_u`。必要性证书为
```
NC_u = ( Δ̂_u, L_u, p_u, design, cov )
```
若 `L_u > δ_min` 且 `p_u < α`，称 u **必要**，保留；若置信区间整体低于 `−δ_min`（消融反而更好）且显著，u 为**有害**，可中立化；否则 u 为**未定**——未定的非安全单元按保守原则保留（不得凭"看起来没用"删除）。所有 `u∈P_prot` 永远保留。NC 之外不得以任何叙事理由保留或删除模块。

**定义 590（角色反事实一致性 Role-Counterfactual Consistency）** 对角色 ρ 或替换 `ρ→ρ'`，定义反事实预测
```
E_pred(ρ off) = E_{model}[ J(full) − J(full \ ρ) ],   E_pred(ρ→ρ') = E_{model}[ J(ρ') − J(ρ) ]
```
在安全包络（定义 591）内测得 `E_obs`，并做
```
RCCf(ρ) = consistent  若 |E_obs − E_pred| ≤ ε_rcc 且方向一致
        = redundant  若 E_obs ≪ E_pred（实测几乎无变化，预期有显著变化）
        = leak       若 E_obs ≫ E_pred，或变化出现在未声明维度 D_out
        = underdetermined  若置信区间跨 0 且样本不足
```
`redundant` 指向角色重叠（可合并/精简），`leak` 指向职责越界（必须收紧角色边界）。二者都不是"证书可放宽"的理由。

**定义 591（角色消融安全包络 Role-Ablation Safety Envelope）** 反事实实验的安全包络为
```
Env = { (config, ρ, op) : 配置通过 v12 全部适用证书
                          ∧ 处于影子模式/低速微扰/证书等价孪生
                          ∧ 不进入主执行路径 ∧ 不修改任何真实阈值
                          ∧ 可由 P^g 在 τ_abort 内安全中止 }
```
包络之外的任何角色移除/替换只允许在纯仿真或离线回放中进行，且结论只能用于生成假设，不能进入 NC 或 RCC。

**定义 592（角色—消融共享状态）**
```
ζ_ra = ( ρ_t, RCC, G_abl, NC, B_abl, history )
```
RCG 写 `ρ_t,RCC`；ANC 写 `G_abl,NC`；RCP 读 `ρ_t,RCC` 并写 `history` 与修订建议；RAC 读全部并写调度建议；NCP 在 `ζ_ra` 上做最终选择。五者共享同一状态，避免"角色、消融、规划"各自维护不一致的假设。

**定义 593（中立元表 v13 扩展）**

| 新组件 | v^⊥ | 等价退化点 |
|---|---|---|
| RCG | 单一 `role=executor`，义务/权限=全部 v12 能力，无资源/交接约束 | Level-4（v12 单执行者路径） |
| ANC | 保留 v12 全部模块，无必要性门控，无中立化 | Level-3（v12 模块集） |
| RCP | 只静态 RCC，无 `do(ρ off)`/`do(ρ→ρ')` | Level-2（v12 + 静态角色检查） |
| RAC | 由 v12 GAGP/NCP 直接选角色与技能，消融仅事后审计 | Level-1（v12 决策路径） |

**定义 594（通用技能的角色标注，升级定义 581）** v12 的 `π_u=(τ,β,π_h,effect,pre,post)` 追加 `role_tag` 与 `obligation_ref`：
```
π_u^RA = ( τ, β, π_h, effect, pre, post, role_tag, obligation_ref )
```
`role_tag` 只是索引，不改变 π_h 的执行语义；它使 RCC 能把每个展开后的 v11 HAS 归到某个角色义务上。v12 技能是 `role_tag=executor, obligation_ref=⊥` 的特例。

**定义 595（角色—消融感知选择 Role-Ablation-Aware Selection）** NCP/RAC 在 v12 选择目标上追加角色与证据项：
```
max_{ρ_t, g}  E[Progress(g)] − λ_risk·U_gap(g) + λ_info·InfoValue(g)
              − λ_role·(1−RCC_margin(ρ_t)) − λ_abl·Uncert(NC)
s.t.          v12 全部证书有效
              RCC(ρ_t)=ok（或仅含可安全修复的软违规）
              Σ U_gap ≤ B_transfer
              P^g(g) ≠ ∅
              Σ cost(ablation) ≤ B_abl
              P_prot 不被任何 op 触及
```
其中 `RCC_margin` 为定义 585 的余量，`Uncert(NC)` 为未定单元的不确定性惩罚。角色/消融项只参与排序与预算，不新增或放宽任何执行证书。

**定义 596（联合角色一致性 Joint Role Consistency）** 对并发角色集 `R={ρ_1,…,ρ_k}`，联合一致性为
```
RCC_joint(R) = RCC(ρ_1) ∧ … ∧ RCC(ρ_k) ∧ Ĉ_joint(shared resources) ∧ Acyclic(E_pre) ∧ HandoffCoverage
```
并要求"联合可行性"不能被逐角色一致性的简单合取替代：共享物体/工作空间/接触力必须使用联合证书 `Ĉ_joint`，否则记为"伪一致"（各角色单独看都安全、合在一起越界）。

## 2. 形式化升级（要点）

**升级定义 571/581（通用技能）** `π_u → π_u^RA`。角色标注只是索引，USG 展开仍逐项落到 v11 HAS，故 HCC/CC 仍可逐项检查。

**升级定义 575/576（gap 证书）** 证书合取升级为
```
Ĉ_joint^RA = Ĉ_contact ∧ Ĉ_h ∧ Ĉ_gap ∧ RCC ∧ RCCf
P^joint^RA = P^c ∩ P^h ∩ P^g ∩ P^ρ
```
`P^ρ` 为"角色一致且有安全回退角色"的点集；RCC/RCCf 只做附加过滤，不替代任何 v12 证书。

**升级定义 589/590（选择与中止）** 执行段的必要条件升级为：v12 中止点非空 **且** 角色一致 **且** 存在受证的回退角色。回退角色本身必须通过 RCC 与全部 v12 证书。

**升级消融实践（E625/E626 → E627–E646）** 消融从"单因子事后比较"升级为"预注册协议 + 因子设计 + NC + 对角色作单元 + 对本轮自身做完整 2³ 因子消融"。

# IP-381 RoleConsistencyGovernor
class RoleConsistencyGovernor:
    def __init__(self, role_types, cert_store, uc, margin_min=0.05):
        self.roles = role_types        # 定义 583
        self.certs = cert_store        # v12 证书查询
        self.uc = uc
        self.m = margin_min

    def certify(self, rho_t, role_graph):
        V, margins = [], []
        for a, role in rho_t.items():
            # 1 capability
            if not self.certs.covers(role.cap, a):
                V.append(("cap", a, role))
            # 2 authority
            for g in role.owned_skills:
                if not role.auth.allows(g) or not self.uc.supports(g.binding):
                    V.append(("auth", a, g))
            # 3 effect / drift (定义 586)
            d = self._drift(role, a)
            if d > self.m:
                V.append(("drift", a, d))
            margins.append(1.0 - d)
        # 4 resource / joint cert (定义 596)
        if not self._joint_resource_ok(rho_t, role_graph):
            V.append(("resource_joint", role_graph.conflicts))
        # 5 temporal
        if has_cycle(role_graph.E_pre) or not edf_feasible(rho_t, role_graph):
            V.append(("temporal", role_graph.E_pre))
        # 6 handoff
        for (i, j) in role_graph.E_hand:
            if not implies(role_graph.post(i), role_graph.pre(j)):
                V.append(("handoff", i, j))
        return RCC(ok=not V, margin=min(margins) if margins else 1.0,
                   violations=V, coverage=self.certs.coverage())

    def filter_assignments(self, candidates, role_graph):
        return [r for r in candidates if self.certify(r, role_graph).ok]


# IP-382 AblationNecessityCertifier
class AblationNecessityCertifier:
    def __init__(self, protected, alpha=0.05, delta_min=0.01):
        self.protected = set(protected)     # P_prot：不可消融
        self.alpha = alpha
        self.delta_min = delta_min
        self.registry = {}                  # hash(P_abl) -> protocol

    def register(self, protocol):
        assert not (set(protocol.units) & self.protected)
        h = stable_hash(protocol)
        self.registry[h] = protocol
        return h

    def run(self, protocol_hash, runner, budget):
        proto = self.registry[protocol_hash]
        assert stable_hash(proto) == protocol_hash   # 预注册不可篡改
        design = make_design(proto.D, proto.U, budget)   # 因子/序贯
        rows = []
        for cfg in design:
            units = set(proto.U) - set(cfg.ablated)
            assert not (units & set())  # 只跑安全配置
            rows.append(runner.evaluate(units, cfg.seed, shadow=cfg.shadow))
        effects = analyze_factorial(rows, design)     # 主效应 + 交互项
        nc = {}
        for u in proto.U:
            d_hat, lcb, p_raw = marginal(proto.D, effects, u)
            p_adj = holm_adjust(p_raw, len(proto.U))  # FWER ≤ α
            nc[u] = NC(d_hat=d_hat, L=lcb, p=p_adj,
                       design=proto.D, cov=design.coverage)
        return nc

    def gate(self, nc):
        # 只对非安全单元给出保留/中立化决定
        neutralized = {u for u, c in nc.items()
                       if u not in self.protected
                       and c.L < -self.delta_min and c.p < self.alpha}
        # 未定/必要的非安全单元一律保留
        return neutralized


# IP-383 RoleCounterfactualProber
class RoleCounterfactualProber:
    def __init__(self, model, guard, env, eps_rcc=0.05):
        self.model = model          # v12 孪生 + RCC 预测器
        self.guard = guard          # v12 证书 + 安全包络
        self.env = env              # 定义 591
        self.eps = eps_rcc

    def probe(self, rho_t, rho, op, samples):
        if not self.env.allows(rho_t, rho, op):
            return RCCf("out_of_envelope")
        e_pred = self.model.predict_delta(rho_t, rho, op)      # 定义 590
        e_obs, ci = self._shadow_measure(rho_t, rho, op, samples)
        if not self.guard.certifies_shadow(0):                 # 影子也必须安全
            return RCCf("unsafe_shadow")
        if ci_crosses_zero(ci) and samples < min_samples(e_pred):
            return RCCf("underdetermined", e_pred, e_obs)
        if abs(e_obs - e_pred) <= self.eps and same_sign(e_obs, e_pred):
            return RCCf("consistent", e_pred, e_obs)
        if abs(e_obs) < self.eps and abs(e_pred) > self.eps:
            return RCCf("redundant", e_pred, e_obs)
        if undeclared_dimension_changed(e_obs, rho) or e_obs > e_pred + self.eps:
            return RCCf("leak", e_pred, e_obs)
        return RCCf("inconsistent", e_pred, e_obs)

class RoleAblationCoordinator:

## 4. 推导

**引理 113（角色一致性下的技能替换传播）** 设角色 ρ 内某技能项在类型 τ 下对绑定扰动 L-Lipschitz，`β≃_ε β'`，且 RCC 的效果余量为 m。则替换后角色一致性的余量下降满足
```
Δm ≤ L·ε + 2δ_h ,
```
其中 δ_h 为 π_h 在 v12 下的模型误差。证明：由定义 573 的 ε-等价，效果度量差 ≤ε；L-Lipschitz 放大到 ρ 的声明效果维度；两侧各叠一次 π_h 误差，再与定义 585 的第 6 项比较。∎ 推论：v12 的绑定替换必须同时看 gap 证书与该角色的一致性余量，只过 TGC 不代表角色仍一致。

**引理 114（单因子消融的交互偏差界）** 设真实必要性为 `Δ_u = E[J(full)−J(full\u)]`，而单因子顺序剪枝在已移除集合 R 后的当前系统 S 上测得 `m_u = J(S)−J(S\u)`。则
```
| m_u − Δ_u | ≤ Σ_{v∈R} | I_{uv} | + O(Σ_{v,w∈R}|I_{uvw}|) ,
```
其中 I 为真实与仿真/影子交互项之差。证明：把 J 按包含—排除（Möbius）展开，m_u 与 Δ_u 的差恰为所有含 u 与 R 中单元的交互项之和；截断到二阶即得主界。∎ 推论：**单因子消融在强交互系统中系统性有偏**；偏差大小等于"已删单元 × 待测单元"的交互质量，故必须做因子设计或明确保留交互预算。

**引理 115（因子设计的分辨率—可辨识性）** 对 k 个单元采用分辨率 IV 的 `2^{k−p}` 部分因子设计，若三阶及以上交互可忽略，则全部主效应与二阶交互可辨识，且
```
n_design = 2^{k−p} = O(2^k / 2^p) ,   p ≥ k/2（存在性）
```
即预算从全因子 `2^k` 降到 `O(2^{k/2})` 仍能分离主效应与二阶交互。证明：分辨率 IV 的定义关系字长 ≥4，故主效应不与任何二阶交互混杂；在三阶可忽略假设下，用标准正交对比估计。∎ 推论：ANC 默认设计应为分辨率 IV/序贯，而不是逐单元 after-the-fact 删除。

**引理 116（必要性证书的多重比较控制）** 若对 m 个非保护单元分别以 Holm 逐步法在水平 α 下检验，则
```
P( 至少一个假阳性必要结论 ) ≤ α ,
```
且 `L_u` 为相应单侧置信下界。证明：Holm 控制族错误率（FWER）；单侧 LCB 由同一次检验的对偶性得到。∎ 推论：候选单元越多，单个 NC 越保守；这是"消融越多、结论越弱"的代价，必须用预注册固定单元集来约束。

**引理 117（安全继承与不可绕过性 v13）** 定义 v13 执行集
```
Exec_RA = { (ρ_t,g) : v12 物理/接触/谐波/规范/gap 证书有效
                     ∧ RCC(ρ_t)=ok ∧ RCCf 无 leak
                     ∧ ΣU_gap≤B_transfer ∧ P^g≠∅
                     ∧ (ρ_t,g) 展开后不触及 P_prot 的移除 }
```
则 `Exec_RA ⊆ Exec_v12`（按展开后的 v12 执行序列比较）。证明：RCG 只过滤角色赋值，ANC 只离线中立化非保护单元，RCP 只影子运行并发信号，RAC 只排序；四者均不写真实证书，故任一 `(ρ_t,g)∈Exec_RA` 展开后逐项满足 v12 证书，属于 v12 执行集。∎ 因此 v12 引理 109 与 v11 引理 101/95 的安全继承在 v13 上继续成立。

**引理 118（中立元退化等价 v12）** 将定义 593 的四个中立元分别注入 RCG/ANC/RCP/RAC 端口，则角色过滤退化为单执行者、模块集保持 v12、无角色反事实、选择退化为 v12 NCP；主闭环调用序列与 v12 逐位一致，再沿 v12 链退回 v11/v10/v9/v8/v7/v6。证明：逐端口代入定义 593 即得；四端口互不相交，中立元不改变任何 v12 证书检查。∎

**引理 119（预算守恒 v13）** 新增在线成本上界：RCG 角色一致性 ≤0.5ms（角色数 ≤8、证书查表、资源冲突图 ≤16 边，50Hz）；角色守卫 ≤0.2ms；RAC 排序 ≤1ms（与 v12 GAGP 共享候选）。ANC/RCP 全部离线/影子，在线摊销 ≤0.1ms。总决策 p99 仍 ≤22ms，50Hz 保持（v12 留有 2ms 余量）。证明：逐项复杂度代入并做静态 EDF 校验 `ΣŴ_m≤B_dec`。∎

**引理 120（可替代角色下的必要性下界）** 若角色 ρ_1,ρ_2 相互 ε-可替代（ρ_2 能在效果差 ≤ε 内覆盖 ρ_1 的 resp），则单独移除 ρ_1 的必要性效应
```
Δ_{ρ_1} ≤ ε ,
```
故任何 `δ_min>ε` 的 NC 都无法宣称 ρ_1 必要；必须改用替换设计 `do(ρ_2→ρ_1)` 或联合消融 `do({ρ_1,ρ_2} off)`。证明：移除 ρ_1 后 ρ_2 接管其义务，系统性能至多变化 ε；故边际效应被替代性吸收。∎ 推论：**角色消融不是模块消融**；对可替代角色做"移除即必要"的推断会系统性低估或高估，必须报告替代结构。

**引理 121（角色反事实的检验功效）** 设角色泄漏导致的真实行为差为 δ，影子测量噪声标准差 σ，影子保真误差上界为 ε_s（`|E_obs−E_true|≤ε_s`），双侧水平 α、功效 1−β 的检验至少需要
```
n ≥ 2 (z_{1−α/2} + z_{1−β})² σ² / (δ − ε_s)² ,   且须 δ > ε_s
```
个影子样本；若 `δ ≤ ε_s`，无论样本多少都无功效。证明：标准两样本均值检验功效公式，叠加保真误差把有效效应从 δ 降为 δ−ε_s。∎ 推论：**影子保真度就是反事实的分辨率下限**；RCP 必须先认证 `ε_s`，否则"一致"可能只是双方都看不清。

## 8. 已知风险与失效模式

1. **角色定义的自我实现**：角色义务与 RCC 谓词由研究者设定，若设定本身遗漏了真实风险维度（如"旁观者"角色对共享工作空间的隐性占用），系统会一致地"通过"检查。缓解：未声明维度审计、RCP 的 `leak` 捕捉、红队角色、跨团队角色本体对照。
2. **预测与实测同错（自洽失败）**：RCP 的 `E_pred` 由同一套角色/孪生模型生成，模型偏差可能让"一致"变成"同样错"。缓解：独立影子测量、保真误差 ε_s 显式认证、外部锚点、预测区间而非点估计。
3. **角色可替代性混淆必要性**：可相互替代的角色在单因子移除下显示"不必要"，联合消融又会因过度移除而夸大。缓解：替换设计、联合消融、报告替代结构（引理 120）。
4. **消融协议被事后解释污染**：研究者看到结果后调整单元、指标或停止规则。缓解：协议 hash 锚定、盲分析、预注册单元集、NC 作废机制。
5. **多重比较与低功效**：单元多、样本少，Holm 校正后全部"未定"，ANC 无法做出任何保留/中立化决定。缓解：分层预注册、序贯设计、优先高信息单元、显式报告"未定"而非强行结论。
6. **影子模式保真不足**：低速/影子配置与真实高速接触差异大，RCP 的 `E_obs` 无法代表真实行为。缓解：证书等价孪生、保真误差上界、只在包络内下结论、把"不可安全反事实"记为一等未知。
7. **角色粒度与活性权衡**：角色划得过细导致 RCC 可行集清空、频繁 `a_ask`；过粗则掩盖越权。缓解：分层角色、动态合并/拆分、RCC 软违规的显式分级、回退单角色。
8. **受保护集被间接绕过**：ANC 虽不能移除安全单元，但可通过中立化其"输入角色/接口"间接削弱。缓解：把输入依赖纳入受保护集闭包、依赖图审计、E638 对抗测试。

## 9. 本轮最大风险

**一句话**：角色边界与消融模型都由同一套有限团队/任务分布拟合而来，RCP 又用这套模型生成"预测"，于是角色定义的系统性错误可能**自洽地通过**反事实检验（预测与实测同错），而交互感知消融仍可能被"角色可替代性"混淆，最终在"角色一致、消融显著"的双重表象下，于未见过的新角色组合上发生越权或交接空窗——即**证据齐全的角色边界失败**。
