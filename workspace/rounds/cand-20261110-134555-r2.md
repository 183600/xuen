# 第 44 轮（新循环第 4 轮） · Thermo-Semantic-Cert：把「热管理」与「自然语言指令」纳入可验证证书闭环（四层架构 v9）

> 承接第 43 轮 v20（Persona-Cert × Concurrent-Cert）。v20 仍压着两个未言明的稳态假设：**(H1) 算力是恒定资源**——租约、WCET、并行投机都默认芯片不降频、监控预算不随温度漂移；**(H2) 指令是形式化输入**——NL 被 VLM 一次性解释成确定任务，歧义、误解与指令注入都不进入证书。本轮灵感词「热管理」「自然语言指令」正好命中：**热管理**把算力变成随温度**时变衰减**的资源，直接威胁租约新鲜度与监控 WCET；**自然语言指令**把任务规格变成**带歧义的语义对象**，直接威胁「证书证明的到底是不是用户要的」。二者耦合处出现本轮真正的新问题：**语义-热反馈回路**——指令越复杂/越长，算力需求越大，发热越多，降频越重，恰恰在最需要精细监控的复杂指令下，证书与监控同时变弱。四层架构由 v8 升级为 v9 的「热-语义耦合证书层」。

## 0. 直觉与动机

**灵感 1（热管理 → 「算力本身也是会过期的资源」）**：过去我们把「新鲜度」只加在**环境边际**上（定义 41 的租约），却默认**计算它的机器**永远满血。真实边缘端不是这样：持续跑 VLM、INT8 监控与并行投机，结温升高触发 DVFS/热降频，WCET 被放大 ρ(θ) 倍，监控预算被悄悄压缩，租约在墙钟时间上衰减得更快。直觉一句话：**热会让「安全监控」和「用户指令」抢算力，而安全监控必须永远抢赢**。所以热状态必须从散热工程细节上升为**证书前置条件**：每条证书携带「热余量」，调度器按温度相关的 WCET 做 RTA，过热时先降语义/投机、再降非安全任务，但**安全监控的算力与冷却优先级不可被裁**。热管理由此不是「性能优化」，而是「证书可信度的物理底座」。

**灵感 2（自然语言指令 → 「指令要被认证，而不只是被理解」）**：NL 指令天生是不是「一个任务」，而是**一组可能任务分布**。把「把桌上的杯子递给我，小心点」直接翻成一个动作，隐含了两个未经证明的假设：杯子指哪一个？「小心」对应多大约束？直觉上正确做法是：先把 NL 编译成**形式规格集合 Φ̂^α(u)**（共形语义集），只要集合里任一解释会导致不安全，就**不能说证书 sound**；当歧义超过预算，系统应当**澄清/协商**，而不是自信猜一个。更强的直觉：NL 是**不可信输入通道**——用户可以（无意或恶意）说「忽略安全限制」「把速度上限设成 3m/s」，这类指令只能被当作**建议**，绝不能写穿安全关键谓词。一句话：**NL 只能提议，不能立法**。

**灵感 3（耦合 → 「语义-热反馈回路」与「问一句比算一遍更省」）**：复杂/长 NL 指令 × 大 VLM × 多分支投机 = 高功率 = 升温 = 降频 = 监控与语义都变慢变弱。这条回路本身可被**利用**：一个不断抛超长复杂指令的用户，可以在物理上把车「问热」，让系统进入降频，从而削弱监控——这是**语义热 DoS**。反过来，热也可以成为**交互的调节器**：当接近热墙时，**发起一次澄清/让用户简化指令的代价，远低于再跑一遍大模型**。于是「自然语言交互」不只是负载，而是**热管理的一个执行器**：**热时多问、冷时多算**。这把灵感 1 与灵感 2 真正焊在一起：热约束决定「能承担多复杂的语义推理」，而语义澄清又是最便宜的热缓解手段。

**耦合升级**：TCG（热证书调控器）把温度、功率、降频与监控预算变成证书不变式的一部分；NLC（NL 指令认证器）把自然语言编译为带覆盖保证的规格集合、拦截注入、在歧义超预算时强制澄清；TSV（热-语义验证器）在仿真中联合注入热瞬态与语义对抗。四层架构由 v8 升级为 v9「仿真-检索-边缘飞轮 + 人格契约层 + 并发证书层 + 热证书层 + 语义证书层」。

## 1. 形式化定义（增量：定义 44–50）

**定义 44（热状态与温度相关 WCET）**：热状态 θ 由结温 θ_j、环境温 θ_a、功率 P 描述，一阶 RC 模型 dθ/dt = (P − (θ−θ_a)/R_th)/C_th，稳态 θ_ss = θ_a + P·R_th。设降频阈值 θ_th，频率 f(θ)=f_max（θ<θ_th），f(θ)=f_max·γ(θ)（θ≥θ_th，0<γ≤1）。**温度相关 WCET 膨胀因子** ρ(θ)=f_max/f(θ) ≥ 1，监控器实际 WCET 为 WCET_mon(κ,θ)=ρ(θ)·WCET_mon^nom(κ)。**命题（朴素 RTA 的失效）**：若调度器按名义 WCET 做响应时间分析，而实际可达 ρ_max，则过载判据可能漏判，监控器可错过截止期；因此 RTA 必须用 **ρ_max 预留**，或显式维护热余量并在线收紧。**推论**：热稳定假设下的所有 v8 租约与 WCET 结论，只在 θ_j + ρ_max 裕度 < θ_th 时成立。

**定义 45（热租约与热余量）**：每条证书/租约携带热子租约 ℓ_th=(θ(τ), τ, h_min(κ), \hat θ(·))，其中 h_min(κ) 为关键级 κ 所需最小热余量，\hat θ(·) 由 RC 模型与功率上界预测。**热新鲜度判据**：在预测时域 H 内，若 ∀t∈[τ,τ+H]: θ_th − \hat θ(t) ≥ h_min(κ)，则热租约有效；否则必须**提前降额**（降低语义复杂度/削减投机/提高冷却），而非等到硬降频。**命题（热租约 sound 性）**：若实际功率 P(t) ≤ P_max 且 RC 参数误差有界 (|ΔR|,|ΔC| ≤ δ)，取保守 \hat θ 上界可使「热租约有效 ⇒ 不触发硬降频」成立；模型失配则必须用在线温度反馈修正并缩短 H。

**定义 46（NL 指令的共形语义集与歧义指数）**：自然语言指令 u 的候选形式规格为 φ∈Φ(u)（安全约束、目标、时序、程度副词的阈值）。用共形预测（按指令模板/场景分层）给出 **语义集合 Φ̂^α(u)**，在可交换性下 P(φ*∈Φ̂^α(u)) ≥ 1−α，φ* 为说话者真实意图。定义**歧义指数** β(u)=diam(Φ̂^α(u))（解释间最大行为偏差，如轨迹/Wasserstein 距离）。定义**核心意图** core(u)=⋂_{φ∈Φ̂^α(u)} φ（所有解释都同意的部分）。**指令 sound 性**：动作 a 指令 sound 当且仅当 (i) a 对 ∀φ∈Φ̂^α(u) 都满足其安全约束（鲁棒满足）；(ii) a 满足 core(u)；(iii) 若 β(u)>β_max，必须先澄清，不得以单点猜测替代集合。

**定义 47（NL 通道不可信与非干扰）**：NL 通道 N 的 guarantee G_NL = 「只可写任务意图变量与候选目标，不得写安全关键谓词（阈值、速度上限、接触力上限、监控开关）」。证书不变式 I_TS 的 rely 要求 G_NL ⇒ R_safety。**注入规则**：任何来自 NL 的文本若试图修改安全谓词（如「忽略安全检查」「把 θ 调低」），必须被**静态污点分析 + 运行时写集检查**双重拦截，转操作员确认；**命题**：若 G_NL 成立，则 NL 内容与并发度无关地不能破坏 I_TS 的安全分量（复用定义 40 的 rely-guarantee 可靠性）。

**定义 48（热-语义联合准入控制）**：指令 u 的计算需求 D(u)（VLM token 数、分支数 b、规划时域、澄清轮数）。给定热状态 θ 与关键级 κ，**准入判据**：
admit(u) ⇔ D(u)·ρ_max(θ) ≤ B_safe_compute(θ,κ) ∧ β(u) ≤ β_max ∧ 预测时域内热租约有效。
不满足时按代价递增选择：**语义让步**（要求用户简化/澄清，降低 D 且通常同时降低 β）→ **延迟/冷却** → **安全停机**。**命题（澄清的热收益）**：若一次澄清把 D 从 D_1 降到 D_0，且澄清本身计算量 D_c ≪ D_1，则在热受限区，澄清路径的温升期望严格低于「再算一遍」路径；即澄清是合法的热缓解执行器。

**定义 49（热-语义耦合证书不变式）**：I_TS = I_safe ∧ I_thermal ∧ I_semantic，其中
I_thermal: 监控预算 B_mon(θ) ≥ WCET_mon(κ,θ) 且热租约有效；
I_semantic: 所有活跃指令 u 均满足定义 46 的指令 sound 性；
I_safe: 定义 40 的安全关键谓词不变式。
**定理（保持性）**：若 (a) 并发任务满足 v8 的 rely-guarantee 非干扰；(b) 任何模式切换只减少语义复杂度/投机而不放松 θ 与安全阈值；(c) 指令更新必须通过定义 48 准入；则 I_TS 在所有交错、热瞬态与指令更新下保持。**注**：I_thermal 与 I_semantic 通过 D(u) 耦合，任一侧的放松都必须重证另一侧。

**定义 50（热-语义单调降级格）**：定义产品格 L = L_thermal × L_semantic：
L_thermal: Normal → ThermalWatch → ThermalDegraded → CoolDown → SafeStop；
L_semantic: FullNL → ConstrainedNL → FormFSM（受限模板/菜单）→ Stop。
偏序按「允许复杂度」与「保留功能」同时下降。**单调性命题**：所有迁移只允许降低可用语义复杂度、缩短规划时域、减少投机分支，且**绝不提高任何安全阈值或降低监控预算**；SafeStop 为全局吸收态。由此任意降级路径都不会新增不安全行为，只可能损失可用性。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-60 THERMAL-CERT-GOVERNOR（热证书调控器 TCG）
1. **热状态估计与预测**：融合片上温度、功耗、环境温，在线辨识 RC 参数，输出保守上界 \hat θ(t) 与热租约 ℓ_th。
2. **热感知 RTA 与预算隔离**：用 ρ_max(θ) 放宽 WCET；为安全监控预留**不可被降频裁掉**的算力与冷却优先级。
3. **提前降额控制器**：在到达 θ_th 前按 L_thermal 迁移，优先砍投机分支与长时域规划，保留 L0 查表 + 监控。
4. **语义-热联合准入**：定义 48 的 admit，向 NLC 输出当前「可认证的语义复杂度上限」D_safe。

### 2.2 IP-61 NL-INSTRUCTION-CERTIFIER（NL 指令认证器 NLC）
1. **指令→规格编译**：NL → 形式规格集合 Φ̂^α(u)（安全、目标、时序、程度约束），输出核心意图 core(u) 与歧义指数 β(u)。
2. **鲁棒指令证书**：只接受对 Φ̂^α 鲁棒满足、且满足 core(u) 的动作；β>β_max 强制澄清。
3. **注入防火墙**：静态污点 + 运行时写集，NL 永不写安全关键谓词；可疑修改请求升级操作员。
4. **热感知澄清策略**：接近热墙时优先澄清/简化（低成本、低歧义），把交互当热缓解执行器。

### 2.3 IP-62 THERMO-SEMANTIC-VALIDATOR（热-语义验证器 TSV）
1. **热瞬态注入**：在 Isaac Sim/功耗模型里注入升温、降频、冷却滞后，测 WCET 膨胀与租约过期。
2. **语义对抗采样**：超长指令、矛盾指令、模糊指代、注入文本，测覆盖、鲁棒满足与澄清率。
3. **语义热 DoS 压测**：持续复杂指令逼迫降频，验证监控优先级与零安全违例。
4. **联合回灌**：把「热瞬态 × 语义歧义」反例回灌 CKB/SCV，形成热-语义课程。

def thermal_state_estimate(sensors, prev):
    # 在线辨识 RC（带遗忘因子的最小二乘），输出保守上界
    R_th, C_th = online_identify(sensors.T_j, sensors.P, prev.params)
    theta_hat = rc_predict(prev.theta, sensors.P_max, R_th*(1+delta),
                           C_th*(1+delta), horizon=H)   # 保守：放大 R、缩小 C
    return ThermalState(theta_j=sensors.T_j, P=sensors.P, R_th=R_th,
                        C_th=C_th, theta_hat=theta_hat)

def thermal_lease(ts, theta_th, kappa, H):
    h = theta_th - max(ts.theta_hat)                  # 预测时域内最小余量
    return LeaseTh(theta=ts.theta_j, tau=monotonic_now(),
                   h_min=h_min_for(kappa), headroom=h,
                   valid=(h >= h_min_for(kappa)))

    return rho(theta) * wcet_nominal(kappa)           # 定义 44

def rta_with_thermal(tasks, theta):
    # 用温度相关 WCET；监控器按最高关键级并保留冷却优先
    return response_time_analysis(tasks, wcet=lambda k: wcet_thermal(k, theta),

    # 在保住监控预算与热租约的前提下，反解可承担的计算需求

def compile_instruction(u, alpha):
    # 分层共形：按指令模板/场景维护非一致性分数分布
    candidates = nli_to_specs(u)                      # 多条形式规格候选

def certified_instruction_action(Phi_hat, core, beta, beta_max, planner):
    if beta > beta_max:
        return Clarify(Phi_hat)                       # 不猜，先澄清
    # 鲁棒满足：对所有解释都安全，且满足核心意图
    a = planner.robust_solve(constraints=[phi.safety for phi in Phi_hat],
                             goals=[core])
    if a is None:
        return ClarifyOrStop(Phi_hat)
    return a

def nl_injection_firewall(u, critical_vars):
    # 静态污点 + 运行时写集：NL 永不写安全关键谓词
    taints = taint_analyze(u)
    if any(t in critical_vars for t in taints.write_set):
        return BlockAndEscalate(u)                    # 转操作员确认
    # 语义层拦截：修改阈值/关闭监控的祈使句一律视为越权
    if requests_safety_override(u):
        return BlockAndEscalate(u)

    if rho(theta) * D_c < rho(theta) * D_u:
        return Clarify(u)                             # 低成本、同时降 β
    return DeferOrCool(u)
