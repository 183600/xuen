# 想法区 · 第 4 轮：从 X-DUB/PC 到 X-DUB/CI

**灵感词**：indexing / competitive ratio / resource-aware algorithm  
**起点**：v0.3「X-DUB/PC」。它已经有打包核、证书阶梯、证明树，也诚实地承认了两个软肋：窗口搜索是启发式的，且优先约束密集时核往往找不到。本轮不推翻它，而是从它的定义里做一次「消元」。

## 一句话直觉：窗口是表象，瓶颈对才是索引

v0.3 的 `L_PC` 写成一个存在性定义：

```text
1 + max { H : 存在窗口 [a,b) 使 BP(X(a,b,H), m, b-a) 不可行 }
```

这个定义里有两个可以消掉的东西：**H** 和**窗口**。固定一个任务子集 `X`，最好的窗口其实有闭式：

```text
a = min_{i∈X} lo_i
C = C*(X)          # 把 X 装进 m 个箱子所需的最小容量
b = a + C - 1
H* = a + min_{i∈X} q_i + C - 1
```

于是 `X` 能证明的下界就是

```text
B(X) = min lo(X) + min q(X) + C*(X).
```

为什么？若 `H ≤ B(X)-1`，取窗口 `[a, a+C*(X)-1)`；`X` 中每个任务都被 `lo_i ≥ a` 和 `H-q_i ≤ b` 强制在窗口内，而长度为 `C*(X)-1` 的窗口装不下 `X`（装箱不可行）。反过来，任何窗口证书的 `H` 也不会超过这个值。H 和窗口都被消掉了。

更进一步，最优的 `X` 不必是任意子集：取 `i=argmin lo`、`j=argmin q`，把**所有** `lo_k≥lo_i` 且 `q_k≥q_j` 的任务都放进去，得到一个「支配矩形」

```text
R_{ij} = { k∈R : lo_k ≥ lo_i, q_k ≥ q_j }.
```

它比原来的 `X` 更大，`min lo` 和 `min q` 不变，装箱只会更难，所以 `B(R_{ij}) ≥ B(X)`。于是**整个打包核下界只需枚举 O(n²) 个瓶颈对 (i,j)**，不需要窗口、不需要 H 扫描。这就是本轮「indexing」的字面含义：用 `(min lo, min q)` 这对瓶颈给核心建索引。

## 第二个直觉：核心内部还有优先约束

`C*(X)` 是装箱，它把 `X` 看成一堆可任意并行的工件。但 `X` 诱导出的子图仍然有优先约束。把 `C*(X)` 换成 `OPT_X`——`X` 诱导子问题的最小 makespan——门槛就会抬高：

```text
B_P(X) = min lo(X) + min q(X) + OPT_X.
```

因为 `OPT_X ≥ C*(X)`，所以 `B_P(X) ≥ B(X)`。这不是一个小修补：v0.3 的随机 DAG 实验只有 3/30 改进，正是因为它只看得见装箱；而 `OPT_X` 把「核心内部的先后顺序」也算了进去。核心不再是一个装箱实例，而是一个**更小的调度实例**——这正是「recursive core / 子问题索引」的起点。

## 第三个直觉：状态里的机器不是同时空的

到了 B&B 的内部状态，机器 `k` 要到 `A_k` 才可用。v0.3 的窗口容量统一写成 `b-a`，等于假设所有机器在整个窗口都空着。把子问题换成「机器 `k` 从 `max(a,A_k)` 开始可用」的带释放时间子问题，最小完成时间记作 `T(X;σ)`，门槛变成

```text
B_A(X) = T(X;σ) + min q(X).
```

同样的窗口论证仍然成立。这个形式统一了三件事：

- `T=a+OPT_X`：优先约束核（根节点）；
- `T=a+C*(X)`：v0.3 的打包核；
- `T=b*(X,a)`：机器可用时间感知的异构装箱核。

所以在根节点，新算法至少不弱于 v0.3 的打包核；在内部状态，它能看见 `A_k` 造成的容量缺口。一个手算例子：`m=2`，剩余四个任务 `p=(5,6,6,6)`，两台机器都要到 6 才空。v0.3 的 `L0=L_PC=12`，`B_A=18`，而 18 正是这个状态的 OPT。

## 三个灵感词分别补什么

- **indexing**：把核心索引到瓶颈对 `(i,j)` 和支配矩形 `R_{ij}`；用 bitset / 二维前缀和枚举 O(n²) 个候选；用子问题缓存把「同一个核心」在不同节点复用。索引不是搜索加速器，而是把「存在 H/窗口」的定义变成一个可直接求值的闭式。
- **competitive ratio**：定义**有证书的竞争比** `ρ=U/L`。因为 `L≤OPT≤U`，所以 `U/OPT≤U/L=ρ`；`ρ` 是算法能写进证书的 incumbent 竞争比上界。对证书族本身，若 `C*(X)`/`OPT_X` 精确，索引相对理想族是 **1-competitive**（没有搜索损失）。我们不声称新的最坏情况近似比；Graham 的 `2-1/m` 仍是上界保证。
- **resource-aware algorithm**：`T(X;σ)` 显式包含机器数、机器释放时间 `A_k`、任务工时和内部优先约束；计算侧则按「潜在提升 / 求解成本」分配精确子问题求解和递归深度。既对机器资源感知，也对计算资源感知。

## 核心方案：X-DUB/CI

在 v0.3 上做四处增量：

1. **CORE-INDEX**：新下界 `L_CI(σ)`。用闭式 `B(X)=min lo+min q+C*(X)` 和支配矩形 `R_{ij}`，把打包核从「窗口/H 搜索」变成「O(n²) 瓶颈对索引」。m=2 时 `C*(X)` 用子集和精确求出；m>2 用 DFF 或小核 B&B 给下界。
2. **PREC-CORE**：新下界 `L_P(σ)`。把 `C*(X)` 换成 `OPT_X`，核心变成诱导子问题；小核心精确求解，大核心用 `LB_0=CP/work/DFF/C*` 或递归 `CORE-INDEX` 给下界。它严格强于打包核，并在 3 个 n=7 的稠密 DAG 上把 `L_CI=OPT-1` 推到 `L_P=OPT`。
3. **AVAIL-CORE**：新下界 `L_A(σ)`。把子问题换成带机器释放时间 `max(a,A_k)` 的版本，`B_A=T+qmin`；m=2 时用「二分 b + 子集和」精确求异构装箱阈值；m>2 用小核 B&B/DFF。根节点退化为打包核，内部状态严格更强。
4. **INDEX + PROOF + BUDGET**：证明树新增 `CORE-INDEX` 节点，证书是 `(i,j,X,T_LB,π)`，checker 重算 `lo/q/A`、验证支配矩形和子问题下界；控制器按 `(UB-L)/cost` 给候选排序，按 `(L_cheap-L_global)/cost` 给节点分配精确求解，失败时加深递归/加倍预算。

组合下界：

```text
L_X4(σ) = max( L0(σ), L_D(σ), L_CI(σ), L_P(σ), L_A(σ), L_G(σ) )
```

其中 `L_G` 是 A-aware + precedence 的一般核。关掉 `PREC/AVAIL` 退回 v0.3 的打包核；关掉索引退回窗口搜索；全部打开是完整算法。

## 本轮要验证的命题

1. **闭式等价**：`L_CI` 等于 v0.3 的理想打包核下界 `L_PC^*`（m=2 且 `C*` 精确时逐点相等），因此索引没有损失打包核族的强度。
2. **支配矩形**：对任意 `X`，其 argmin 对 `(i,j)` 给出的 `R_{ij}` 满足 `B(R_{ij}) ≥ B(X)`；所以 O(n²) 个 pair 足够。
3. **优先核严格更强**：存在实例使 `L_P < L_CI = OPT-1` 而 `L_P=OPT`；这是本轮最硬的分离证据。
4. **可用时间核严格更强**：内部状态上 `L_A ≥ L_CI`，且存在 `L_A` 比 `L0=L_CI` 高 6 个时间单位、并等于状态 OPT 的例子。
5. **m=2 核判据精确**：`C*(X)` 由子集和精确求出，索引的搜索竞争比为 1；m>2 的 DFF/小核 B&B 只给安全下界。
6. **证书可检查**：`CORE-INDEX` 的局部规则（重算 lo/q/A、验证矩形、验证子问题下界）足以让 checker 独立接受/拒绝；证明树其余规则不变。
7. **竞争比可证**：`ρ=U/L` 是 `U/OPT` 的上界；`ρ=1` 当且仅当当前 incumbent 已最优（在 `L` 精确的意义下）。
8. **不破坏 anytime 区间**：任意时刻 `L≤OPT≤U`；预算耗尽只让 `L` 偏保守，不会错误剪枝。

## 初步结果与边界

- **6 任务反例**：`m=2, p=(10,8,7,3,2,2)`，`L_CI=17=OPT`；支配矩形取全集合，`C*=17`。闭式一步得到 v0.3 需要窗口+子集和才能得到的证书。
- **90 个小实例**（n≤7, m=2；30 随机 DAG + 30 无依赖 + 30 两层 DAG；本轮新种子）：`L0` 精确 77/90，`L_CI` 89/90，`L_P` 89/90；总间隙从 15 降到 1。`L_P` 在这批小实例上没有额外改进（0/90），因为剩余间隙来自全集合或非 proper 子集。
- **180 个 n=7 稠密 DAG**（边概率 0.3/0.5/0.7）：`L0` 163/180，`L_CI` 175/180，`L_P` 178/180；`L_P>L_CI` 出现 3 次，且 3 次都直接闭合到 OPT。这支持「优先核补的是 precedence-heavy 软肋」这一假设。
- **120 个随机可达状态**（n=6, m=2）：`L_A` 0/120 超过 OPT，117/120 达到状态 OPT；42/120 严格高于统一容量版本，平均提升 2.5 个时间单位。另一个 100 状态样本上，A-aware + precedence 的统一界与 `L_A` 相同（0/100 额外改进），说明状态层的主要收益来自 `A_k`，根层的主要收益来自 precedence。
- **等价/合法性对拍**：50/50 个根实例上 `L_CI` 与穷尽窗口扫描相等；80/80 个状态上 `L_CI`、`L_A` 分别与对应的穷尽扫描相等；6 任务实例的全部 63 个子集满足支配矩形引理；全部 490 个实例/状态上没有出现 `L>OPT`。
- **原型速度**：n=6 的 50 个根实例上，索引约 0.0048s，窗口扫描约 0.0205s（约 4.3×）；80 个状态上 `L_CI` 约 0.004s、`L_A` 约 0.012s，对应穷尽扫描约 0.015s/0.018s。这只是实现 sanity check，不是 benchmark。
- **尚未做**：m>2 的精确核、n≥20 的索引维护、PSPLIB/fork-join、独立 checker 对拍、与 v0.2 完整对偶/流证书的正面对撞。`L_P` 的 3 个严格改进是从随机搜索中挑出的，不代表普遍比例。

## 本轮的一句话最大风险

**当前方案最大的风险是：递归核心索引把下界强度押在「找到并精确求解一个小核心」上，而 O(n²) 候选枚举加递归子问题求解可能让每次下界计算比 v0.3 贵一个数量级；在大型或 m>2 的实例上，它可能既找不到足够强的核心，又因为索引/递归开销拖慢 B&B。**

## 0. 版本关系与本轮增量

v0.3（X-DUB/PC）已经建立：

- `P|prec|Cmax` 的 `(任务,机器)` 动作空间与最优性覆盖；
- 时间价格对偶证书 `L_D`、指数 B&B `X-EXACT`、MCTS 上界、证明树；
- 打包核 `L_PC`：窗口 `[a,b)` 内的强制任务必须装进 `m` 个容量 `b-a` 的箱子；
- 证书阶梯 `ADAPT-CERT`：ER/DFF/核/对偶的自适应组合；
- 一个 6 任务分离例与 90 个小实例的下界对比。

v0.4 **不推翻** 这些结论，只做四处增量：

1. **CORE-INDEX（闭式打包核索引）**：把 v0.3 的
   `1+max{H : ∃窗口 W, BP(X_W,m,|W|) 不可行}`
   改写成对子集的闭式
   `B_CI(X)=min lo(X)+min q(X)+C*(X)`，
   并证明最优子集一定是瓶颈对 `(i,j)` 的支配矩形
   `R_{ij}={k: lo_k≥lo_i, q_k≥q_j}`。
   于是整个打包核只需枚举 `O(n²)` 个 pair，不再扫描 H 和窗口。m=2 时用子集和精确求 `C*(X)`。
2. **PREC-CORE（优先约束核）**：把 `C*(X)` 换成诱导子问题的最优 makespan `OPT_X`，得到
   `B_P(X)=min lo(X)+min q(X)+OPT_X`。
   因为 `OPT_X≥C*(X)`，它严格强于打包核；小核心精确求解，大核心用 `CP/work/DFF/C*` 或递归 `CORE-INDEX` 给下界。它直接针对 v0.3 的 precedence-heavy 软肋。
3. **AVAIL-CORE（机器可用时间核）**：在内部状态，把子问题换成机器 `k` 从 `max(a,A_k)` 可用的版本，最小完成时间记为 `T(X;σ)`，得到
   `B_A(X)=T(X;σ)+min q(X)`。
   根节点退化为打包核/优先核；内部状态严格更强。m=2 时用「二分 + 子集和」精确求异构装箱阈值。
4. **INDEX + PROOF + BUDGET**：新增 `CORE-INDEX` 证明节点；checker 独立重算 `lo/q/A`、验证支配矩形、验证子问题下界。控制器按 `(UB-L)/cost` 排序候选、按 `(L_cheap-L_global)/cost` 分配节点预算，失败时加深递归/加倍预算。

关系：

- 关闭 `PREC/AVAIL`、`C*` 用精确子集和 → 得到 v0.3 的打包核，但**一次索引**求出理想族下界，不需要 H/窗口搜索。
- 关闭 `PREC/AVAIL`、`C*` 只用 DFF → 得到 v0.3 的 DFF 子族，但按瓶颈对索引。
- 全部打开 → v0.4 完整算法；`L=max(L0,L_D,L_CI,L_P,L_A,L_G)`，正确性由各证书的可采纳性保证。

## 1. 问题、符号与旧结论

### 1.1 形式化问题

```text
P | prec | Cmax
```

给定任务集 `V={1,...,n}`、工时 `p_i∈Z_{≥1}`、优先约束 `E⊆V×V`（DAG）、同构机器数 `m`。调度由开始时间 `s_i` 与机器 `μ_i` 组成，满足：

```text
(i,j) ∈ E  ⇒  s_j ≥ s_i + p_i
μ_i = μ_j  ⇒  [s_i, s_i+p_i) 与 [s_j, s_j+p_j) 不重叠
```

目标 `Cmax = max_i(s_i+p_i)` 最小；最优值记 `OPT`。

### 1.2 符号表（v0.4 新增/重定义）

| 符号 | 含义 |

| `σ=(S,A,c)` | 状态：已调度集、机器可用时间、完成时间 |
| `R=V\S` | 未调度集 |
| `C(σ)=max_k A_k` | 状态已完成时间 |
| `lo_i` | 动态 head：残余 DAG 中 `i` 的最早开始，含已调度前驱 |
| `q_i` | 动态 tail：`i` 之后（不含 `p_i`）的残余最长路径 |

### 1.3 复用的 v0.3 结论

以下结论直接继承，不再证明：

- **动作覆盖性**：动作 `(i,k)`（`i∈Ready(σ)`，`k∈{1,...,m}`）在 `t=max(A_k, max_{j∈pred(i)} c_j)` 开始；从根出发的某条动作序列可达到一个最优调度。
- **CP 初始上界**：按 `q_i` 降序的 CP 表调度得到可行 `U_0`，且 `U_0≤(2-1/m)OPT`（Graham）。
- **前沿下界**：若 `F` 覆盖所有「可能优于 `U`」的剩余调度，则 `min_{v∈F} LB(v)≤OPT`。
- **对偶证书**：`g_H(σ,λ)>0 ⇒ H<OPT(σ)`；`L_D` 可采纳。
- **指数 B&B**：`X-EXACT` 在动作树上做 best-first；若因 `F=∅` 或 `L≥U` 终止，则 `U=OPT`。
- **证明树**：`TERMINAL/PRUNED/EXACT/EXHAUSTED` 的局部检查规则可靠。

v0.4 只替换/扩展 `LB` 与 `CERTIFY`，并给证明树加一种叶子证书。

## 2. 动机：v0.3 的三个结构性问题

### 2.1 窗口/H 搜索是定义里的，不是算法里必需的

v0.3 的 `L_PC` 定义含有一个存在量词：

```text
L_PC(σ) = 1 + max { H : ∃ 窗口 [a,b), BP(X(a,b,H), m, b-a) 不可行 }.
```

算法为了求它，要么枚举 `O(n²)` 个事件窗口并对每个候选 H 跑装箱，要么用束搜索近似。前者在大 n 上很贵，后者可能漏掉核心。可是这个存在量词可以**整体消掉**：对固定子集 `X`，最好的窗口和 H 都是 `X` 的函数。这是 §3 的起点。

### 2.2 装箱核看不见核心内部的先后顺序

v0.3 的 `BP(X,m,C)` 把 `X` 看成可任意并行的工件。但 `X` 诱导的子图仍有优先边。一个子集可能在装箱意义下能装进两个容量 `C` 的箱子，却因为内部链式约束需要 `C+1` 或更多。v0.3 的随机 DAG 实验只有 3/30 改进，正是这个盲点的证据。把 `C*(X)` 换成 `OPT_X` 是最直接的修复。

### 2.3 统一容量看不见机器可用时间

在 B&B 的内部状态，机器 `k` 要到 `A_k` 才可用。v0.3 的窗口给每台机器同样的容量 `b-a`；如果 `A_k>a`，这台机器在窗口内的实际容量只有 `max(0,b-A_k)`。一个状态可能有 `A=(6,6)`、剩余工作 23、`H=12`：v0.3 的 `L0=L_PC=12`，但两台机器在 12 前只能提供 12 个时间单位，真实 OPT 是 18。把子问题换成带机器释放时间的 `T(X;σ)` 就能看见这个缺口。

### 2.4 三个问题指向同一个对象

三个问题都可以用同一个「核心」对象描述：

```text
核心 X 的阈值 = min lo(X) + min q(X) + （X 在资源约束下的最小完成时间）.
```

区别只在「资源约束下的最小完成时间」用什么松弛：

| 层 | 子问题度量 | 阈值 | 精确性 |
|---|---|---|---|
| PACK | `C*(X)` | `a+qmin+C*` | m=2 子集和精确 |
| PREC | `OPT_X` | `a+qmin+OPT_X` | 小核心精确，大核心下界 |
| AVAIL-PACK | `b*(X,a)` | `b*+qmin` | m=2 二分+子集和精确 |
| GENERAL | `T(X;σ)` | `T+qmin` | 小核心精确，大核心下界/递归 |

## 3. 闭式打包核索引（CORE-INDEX）

### 3.1 核心阈值

固定状态 `σ` 和子集 `X⊆R`。定义

```text
a(X)    = min_{i∈X} lo_i
qmin(X) = min_{i∈X} q_i
B_CI(X) = a(X) + qmin(X) + C*(X).
```

**引理 1（核心阈值可采纳）**：对任意 `X⊆R` 和整数 `H≤B_CI(X)-1`，从 `σ` 出发不存在 makespan ≤H 的调度。

**证明**：令 `C=C*(X)-1`。由 `C*(X)` 的定义，`BP(X,m,C)` 不可行。取窗口 `[a(X), a(X)+C)`。对每个 `i∈X`：

```text
lo_i ≥ a(X)
H - q_i ≤ a(X)+qmin(X)+C-1 - q_i ≤ a(X)+C-1 < a(X)+C = b.
```

所以 `i` 被强制完全执行在窗口内。若存在 makespan ≤H 的调度，把它的机器分配限制到 `X`，就得到把 `X` 装进 `m` 个容量 `C` 的箱子的可行装箱，矛盾。证毕。

> `C=0` 时窗口长度为 0；非空 `X` 不可能装进长度 0 的窗口，论证仍成立。这对应 v0.3 的 deadline/单任务证书。

### 3.2 支配矩形

**引理 2（支配矩形）**：对任意非空 `X⊆R`，令

```text
i = argmin_{k∈X} lo_k,    j = argmin_{k∈X} q_k,
R_{ij} = { k∈R : lo_k ≥ lo_i, q_k ≥ q_j }.
```

则 `X⊆R_{ij}`，`a(R_{ij})=lo_i=a(X)`，`qmin(R_{ij})=q_j=qmin(X)`，且 `C*(R_{ij})≥C*(X)`。因此

```text
B_CI(R_{ij}) ≥ B_CI(X).
```

**证明**：由 `j∈X` 得 `lo_j≥lo_i`，由 `i∈X` 得 `q_i≥q_j`，所以 `i,j∈R_{ij}`，两个最小值分别在 `i,j` 处取到。`X⊆R_{ij}` 由定义。装箱所需容量对超集单调不减。证毕。

**推论 1**：

```text
max_{X⊆R} B_CI(X) = max_{ i,j∈R, lo_j≥lo_i, q_i≥q_j } B_CI(R_{ij}).
```

只需枚举 `O(n²)` 个「合法瓶颈对」。

### 3.3 与 v0.3 打包核的逐点等价

**定理 1（闭式等价）**：设 `L_PC^*(σ)` 是 v0.3 的理想打包核下界（对所有窗口 `[a,b)`、所有 H 取最大），则

```text
max(C(σ), max_{i,j} B_CI(R_{ij})) = max(C(σ), L_PC^*(σ)).
```

因此 `L_CI(σ) := max(C(σ), max_{i,j} B_CI(R_{ij}))` 可采纳，且 m=2 时与理想打包核族**逐点相等**。

**证明**：

1. **窗口证书 → 子集界**：若窗口 `[a,b)`、`H`、`X=X(a,b,H)` 满足 `BP(X,m,b-a)` 不可行，则 `C=b-a<C*(X)`。取 `i=argmin lo(X)`、`j=argmin q(X)`，有 `a≤lo_i`、`b≥H-q_j`，所以
   ```text
   H ≤ b+qmin(X) ≤ a+C+qmin(X) ≤ a(X)+C*(X)-1+qmin(X) = B_CI(X)-1.
   ```
   于是 `H+1≤B_CI(X)≤max_{i,j}B_CI(R_{ij})`。
2. **子集界 → 窗口证书**：对任意 `X`，取窗口 `[a(X), a(X)+C*(X)-1)`。对 `H=B_CI(X)-1`，`X` 中每个任务被强制在窗口内；`BP(X,m,C*(X)-1)` 不可行。所以 `L_PC^*≥B_CI(X)`。取 max 得反向不等式。

两边都与 `C(σ)` 取 max，证毕。

> 这个定理说明：v0.4 没有发明一个更强的打包核族；它证明打包核族有一个**闭式**，并把「求理想族下界」从「窗口/H 搜索」变成「O(n²) 对枚举」。真正的强度增量来自 §4 的优先核和 §5 的可用时间核。

### 3.4 包含旧下界

**推论 2**：在根节点（`A=0`），`L_CI≥max(LB_CP,LB_W)`。

**证明**：

- 单元素 `X={i}`：`C*(X)=p_i`，`B_CI=lo_i+q_i+p_i`，即 `LB_CP` 的某一项。
- 全集合 `X=R`：`B_CI≥C*(R)≥ceil(W(R)/m)=LB_W`。

在内部状态再与 `C(σ)` 取 max 即可。证毕。

### 3.5 6 任务例子

```text
m=2, p=(10,8,7,3,2,2), E=∅
```

`lo_i=q_i=0`，`C*(V)=17`（因为 `BP(V,2,16)` 不可行，`17` 可行）。取 `X=V`，`B_CI=0+0+17=17`。所以 `L_CI=17=OPT`。v0.3 需要窗口 `[0,16)`、子集和与 H 扫描；这里一步得到。

### 3.6 候选索引的构造

**合法对**：

```text
P = { (i,j) : i,j∈R, lo_j≥lo_i, q_i≥q_j }.
```

**矩形**：

```text
R_{ij} = { k∈R : lo_k≥lo_i, q_k≥q_j }.
```

**快速聚合**：对 `R_{ij}` 需要 `W(R_{ij})` 和 `|R_{ij}|`。把任务按 `(lo,q)` 坐标压缩，建二维前缀和，`O(1)` 查询。

**候选上界**：

```text
UB_CI(i,j) = lo_i + q_j + W(R_{ij}).
```

因为 `C*(R_{ij})≤W(R_{ij})`。若 `UB_CI≤L`，该候选不可能改进，直接跳过。这一步是「资源感知」的廉价预筛。

**去重**：不同 `(i,j)` 可能给出同一个矩形；用 `R_{ij}` 的 bitmask 做键缓存 `C*(X)` / `LB(X)`。

**精确 `C*(X)`（m=2）**：令 `W=W(X)`，`bits` 为可达子集和的 bitset：

```text
bits = 1
for i in X: bits |= bits << p_i
```

`C*(X) = min_{s∈SubsetSums(X)} max(s, W-s)`。最小值在 `W/2` 的前驱和后继处取得：取 `s_low` 为 ≤`floor(W/2)` 的最大可达和，`s_high` 为 ≥`ceil(W/2)` 的最小可达和，返回 `min(max(s_low,W-s_low), max(s_high,W-s_high))`。

**DFF 下界（m>2 / 大核心）**：对 `k≥1`，定义

```text
u_k(x;C) = 1,                 x=C
           1/k,               C/(k+1) < x < C
           0,                 0 ≤ x ≤ C/(k+1)
           +∞,                x > C
```

若 `Σ_{i∈X} u_k(p_i;C)>m`，则 `C*(X)>C`。令 `C_DFF(X)` 为满足该条件的最大 `C`，则 `C*(X)≥C_DFF(X)+1`，于是

```text
B_DFF(X) = a(X)+qmin(X)+C_DFF(X)+1
```

是一个合法下界。DFF 只需 `O(|X|)` 扫描；它是 m>2 时的廉价层。

### 3.7 复杂度

- 合法对枚举：`O(n²)`；bitset 交集 `O(n/word)`，总 `O(n³/word)`；若用二维前缀和求聚合，`O(n²)`。
- 每个候选的精确 `C*`：m=2 时 bitset DP `O(|X|·C_max/word)`；也可用 meet-in-the-middle `O(2^{|X|/2})`。
- 候选数 `O(n²)`；若全部精确求值，最坏 `O(n²·T_C)`，其中 `T_C` 是单次 `C*` 的代价。预筛和去重通常大幅降低实际数量。
- 与 v0.3 相比：v0.3 对每个候选 H 枚举 `O(n²)` 窗口，每个窗口跑装箱；v0.4 只枚举 `O(n²)` 个 pair，且**没有 H 循环**。在根节点上，这是从 `O(n²·U·T_C)` 到 `O(n²·T_C)` 的改进（最坏情况）。

## 4. 优先约束核（PREC-CORE）

### 4.1 定义

对 `X⊆R`，令 `G[X]` 为 `X` 诱导的子图（只保留两端都在 `X` 的边）。`OPT_X` 是 `G[X]` 在 `m` 台机器上的最优 makespan（所有机器从 0 可用，无外部释放时间）。定义

```text
B_P(X) = a(X) + qmin(X) + OPT_X.
```

**引理 3（优先核可采纳）**：对任意 `X⊆R` 和整数 `H≤B_P(X)-1`，从 `σ` 出发不存在 makespan ≤H 的调度。

**证明**：取窗口 `[a(X), a(X)+OPT_X-1)`。对 `i∈X`，由 `H≤a+qmin+OPT_X-1` 得 `H-q_i≤a+OPT_X-1=b`；又 `lo_i≥a`。所以 `X` 被强制在窗口内。任何 makespan ≤H 的调度都会把 `X` 限制成一个长度 ≤`OPT_X-1` 的可行子调度，与 `OPT_X` 的最小性矛盾。证毕。

**引理 4（优先核的支配矩形）**：对任意 `X`，取 `i=argmin lo`、`j=argmin q`，则

```text
B_P(R_{ij}) ≥ B_P(X).
```

**证明**：`a,qmin` 不变；且 `X⊆R_{ij}`，任何 `R_{ij}` 的可行调度限制到 `X` 都是 `X` 的可行调度，所以 `OPT_{R_{ij}}≥OPT_X`。证毕。

**定理 2（优先核可采纳且更强）**：

```text
L_P(σ) := max(C(σ), max_{i,j} B_P(R_{ij})) ≤ OPT(σ),
L_P(σ) ≥ L_CI(σ).
```

若 `OPT_X` 对所有候选精确，`L_P` 是理想优先核族的精确下界。

**证明**：引理 3/4 给可采纳性；`OPT_X≥C*(X)` 给逐点支配，取 max 得 `L_P≥L_CI`。证毕。

### 4.2 三个严格分离实例

以下三个 `n=7, m=2` 实例来自随机稠密 DAG 搜索。每个实例都有 `L_CI<OPT`，而优先核 `L_P=OPT`。

| # | `p` | 核心 `X` | `a` | `qmin` | `C*(X)` | `OPT_X` | `L_CI` | `L_P` | `OPT` |
|---|---|---|---:|---:|---:|---:|---:|---:|---:|
| 1 | `(4,3,1,3,3,4,2)` | `{0,1,2,3,4,5}` | 2 | 0 | 9 | 10 | 11 | 12 | 12 |
| 2 | `(2,3,5,8,7,5,4)` | `{2,3,4,5,6}` | 2 | 0 | 15 | 16 | 17 | 18 | 18 |
| 3 | `(7,1,5,3,6,8,2)` | `{0,1,2,3,4}` | 10 | 0 | 11 | 13 | 22 | 23 | 23 |

边集：

```text
#1: (6,4),(6,2),(6,5),(6,0),(4,0),(2,5),(2,3),(5,1),(3,0)
#2: (0,4),(0,5),(4,2),(4,6),(1,3),(1,5),(1,2),(5,2)
#3: (6,5),(6,3),(6,0),(5,3),(5,1),(5,2),(5,0),(5,4),(3,2),(3,4),(1,2),(1,0)
```

以 #1 为例：全集合的 `C*(V)=10`，所以纯装箱核最多到 10/11；核心 `X` 的 `C*(X)=9`，但它内部的优先约束把最小 makespan 抬到 `OPT_X=10`；加上 `a=2` 得到 12，正好等于 OPT。这个 1 个时间单位的差就是 v0.3 在 precedence-heavy 实例上漏掉的那一类缺口。

### 4.3 递归下界

`OPT_X` 本身是 NP-hard；我们只在 `|X|≤k_exact` 时精确求解，更大的核心用下界。定义层级：

```text
LB_0(X) = max( CP(X), ceil(W(X)/m), C*_DFF(X) )      # 以及对 m=2 可负担的精确 C*
LB_d(X) = max( LB_0(X),
               max_{i,j∈X, R_{ij}⊂X} [ a_X(R_{ij}) + qmin_X(R_{ij}) + LB_{d-1}(R_{ij}) ] )
```

其中 `a_X,qmin_X` 是在诱导子问题 `G[X]` 内的静态 head/tail；`R_{ij}⊂X` 排除全集合以避免循环。`LB_d(X)≤OPT_X` 由归纳证明：`LB_0` 是标准松弛；内层 max 是 `CORE-INDEX` 在 `G[X]` 上的下界；归纳假设 `LB_{d-1}≤OPT_{R_{ij}}`，再用引理 3 的窗口论证。

**算法 `SUB-LB(X,d,B)`**：

```text
1  if |X| ≤ k_exact:
2      return EXACT-SUB(X)                  # 精确 OPT_X + 证书
3  T ← max( CP(X), ceil(W(X)/m) )
4  T ← max(T, C*_DFF(X))                    # m>2 的廉价层
5  if m==2 and |X| ≤ k_bitset:
6      T ← max(T, C*(X))                    # 精确装箱下界
7  if d>0 and B>0 and X⊂R:
8      T ← max(T, CORE-INDEX-SUB(X, d-1, B/2))   # 递归优先核
9  return T
```

- `CORE-INDEX-SUB(X,d-1,·)` 在 `G[X]` 上运行同一套索引：用 `X` 内的静态 head/tail 枚举 pair 和矩形，返回 `OPT_X` 的下界。它不需要外层状态，也不会调用 `X` 自身，所以递归终止。
- 对 `X=R` 不调用递归（否则就是原问题）；`SUB-LB` 第 7 行的 `X⊂R` 保证安全。全集合仍可用 `LB_0` 的 `C*`/DFF/CP。

**定理 3（预算化优先核安全）**：若 `SUB-LB` 返回 `T`，则 `T≤OPT_X`；因此

```text
B_P^alg(X)=a(X)+qmin(X)+SUB-LB(X,d,B)
```

是 `OPT(σ)` 的合法下界。若 `SUB-LB` 精确，则 `B_P^alg=B_P`。

**证明**：`SUB-LB` 的每个分量都是 `OPT_X` 的下界；递归层用归纳。引理 3 把子问题下界转成全局下界。证毕。

## 5. 资源感知核（AVAIL-CORE）

### 5.1 定义

固定状态 `σ`、子集 `X⊆R`、`a=a(X)`。令 `T(X;σ)` 为诱导子问题 `G[X]` 在如下机器环境下的最小完成时间：

```text
机器 k 从 max(a, A_k) 开始可用；
任务 i∈X 的工时为 p_i；
只保留 X 内部的优先边；
外部任务不参与。
```

定义

```text
B_A(X) = T(X;σ) + qmin(X).
```

**引理 5（可用时间核可采纳）**：对任意 `X` 和 `H≤B_A(X)-1`，从 `σ` 出发不存在 makespan ≤H 的调度。

**证明**：取窗口 `[a, T(X;σ)-1)`。对 `i∈X`，`lo_i≥a`；且 `H≤T+qmin-1` 给 `H-q_i≤T-1`。所以 `X` 被强制在窗口内。任何 makespan ≤H 的调度把 `X` 限制成机器 `k` 在 `max(a,A_k)` 之后开始、完成时间 ≤H-qmin≤T-1 的可行子调度，与 `T(X;σ)` 的最小性矛盾。证毕。

**引理 6（可用时间核的支配矩形）**：对任意 `X`，取 `i=argmin lo`、`j=argmin q`，则 `B_A(R_{ij})≥B_A(X)`。

**证明**：`a` 和 `qmin` 不变；`R_{ij}⊇X`，任何 `R_{ij}` 的可行子调度限制到 `X` 仍是 `X` 的可行子调度，所以 `T(R_{ij};σ)≥T(X;σ)`。证毕。

**定理 4（可用时间核可采纳且更强）**：

```text
L_A(σ) := max(C(σ), max_{i,j} B_A(R_{ij})) ≤ OPT(σ),
L_A(σ) ≥ L_CI(σ).
```

根节点（`A=0`）时 `L_A=L_CI`；内部状态通常严格更强。

**证明**：引理 5/6 给可采纳性；任何 `X` 的可行子调度也是装箱可行的，所以 `T(X;σ)≥a(X)+C*(X)`，逐点支配 `B_CI`。证毕。

### 5.2 m=2 的精确异构装箱阈值

`T(X;σ)` 的精确求解是 NP-hard（带释放时间的调度）。但我们至少可以精确求出它的**装箱松弛**，记作 `T_PACK(X;a,A)`：最小的 `b≥a`，使得 `X` 能装进容量为

```text
cap_k(b) = max(0, b - max(a,A_k)),  k=1,...,m
```

的 `m` 个箱子。`T_PACK≤T(X;σ)`，所以用 `T_PACK+qmin` 是合法下界。

m=2 时，`X` 能装进 `(c1,c2)` 当且仅当存在子集和 `s` 满足

```text
W(X)-c2 ≤ s ≤ c1.
```

用 bitset 求可达子集和，二分 `b`：

```text
lo_b ← a; hi_b ← a + W(X) + max_k A_k
while lo_b < hi_b:
    mid ← floor((lo_b+hi_b)/2)
    c1 ← max(0, mid-max(a,A_1)); c2 ← max(0, mid-max(a,A_2))
    if SUBSET-SUM-INTERSECTS(X, [max(0,W-c2), min(c1,W)]):
        hi_b ← mid
    else:
        lo_b ← mid+1
return lo_b          # = T_PACK
```

复杂度 `O(log U · |X|·C/word)`。`m>2` 时用 `PACK-BB`（小核心精确）或 `DFF` 的保守下界。

### 5.3 手算状态例子

```text
m=2, p=(6,5,6,6,6,6), E=∅
状态 σ: S={0,4}, A=(6,6), c=(6,0,0,0,6,0)
R={1,2,3,5}, p_R=(5,6,6,6), lo_i=q_i=0
```

- `L0=max(A)=6`，`LB_W=ceil(23/2)=12`，所以 `L0=12`。
- `L_CI`：`C*(R)=12`（`6+6` 与 `6+5` 两箱），所以 `L_CI=12`。
- `L_A`：两台机器从 6 可用；容量 `cap(b)=b-6`。需要 `2(b-6)≥23`，最小 `b=18`；在 `b=18` 时容量 `(12,12)`，可装 `6+6` 与 `6+5`。所以 `T_PACK=18`，`L_A=18`。
- 状态 OPT：两台机器从 6 开始，23 个工时，容量下界 `6+ceil(23/2)=18`；上面的装法达到 18。所以 `L_A=OPT=18`。

v0.3 的 `L0=L_PC=12` 会留下 6 个时间单位的间隙；`L_A` 直接闭合。

### 5.4 一般核：A-aware + precedence

把 `T(X;σ)` 的精确值用于小核心，大核心用下界：

```text
T_LB(X;σ) = max( T_PACK(X;a,A),
                 a(X) + CP(X),
                 a(X) + ceil(W(X)/m),
                 a(X) + LB_d(X) )
```

其中 `LB_d(X)` 是 §4 的优先核下界（从时间 0 计），`a+LB_d` 是带释放时间的合法下界。对 `|X|≤k_exact` 的 proper 子集，可以直接用精确的 `EXACT-SUB(X,a,A)`（带机器释放时间）替换 `T_LB`。

**定理 5（一般核安全）**：若 `T_LB(X;σ)≤T(X;σ)`，则 `B_G(X)=T_LB(X;σ)+qmin(X)` 是合法下界；`L_G=max(C(σ),max_{i,j}B_G(R_{ij}))≤OPT(σ)`，且 `L_G≥max(L_A,L_P)`（在相同的下界层上）。

**证明**：`T_LB` 的每个分量都是 `T` 的下界；引理 5 的窗口论证。`T_PACK≤T`，`a+CP≤T`，`a+ceil(W/m)≤T`，`a+LB_d≤T`（因为 `LB_d≤OPT_X≤T-a`）。支配矩形同引理 6。证毕。

> 实验上，在 100 个内部状态样本中 `L_G` 与 `L_A` 相同（0/100 额外改进）；这说明状态层的主要收益来自 `A_k`，而 §4 的优先核收益主要集中在根节点/浅层 proper 核心。`L_G` 的价值是统一与可扩展，不是在这批样本上再涨一点。

## 6. 算法 X-DUB/CI

### 6.1 核心索引 `CORE-INDEX`

```text
函数 CORE-INDEX(σ, d, B_core)
────────────────────────────────────────────────
1  R ← V\S; 重算 lo_i, q_i
2  L ← max(C(σ), LB_CP(σ), LB_W(σ))
3  if R=∅ or B_core=0: return L, ∅
4  P ← { (i,j) : i,j∈R, lo_j≥lo_i, q_i≥q_j }
5  PQ ← ∅
6  for (i,j) in P:
7      X ← { k∈R : lo_k≥lo_i, q_k≥q_j }
8      if X=∅: continue
9      UB ← lo_i + q_j + W(X)          # C*≤W
10     if UB > L:
11         push PQ with key (UB-L)/cost(X), payload (i,j,X)
12 while PQ≠∅ and B_core>0:
13     (i,j,X) ← pop max key
14     a ← lo_i; qm ← q_j
15     T_LB, π ← SUB-LB(X, d, B_core, a, qm, A)
16     B ← a + qm + T_LB
17     B_core ← B_core - cost(X)
18     if B > L:
19         L ← B; witness ← (i,j,X,T_LB,π)
20     if L ≥ U: break
21 return L, witness
```

`cost(X)` 是估计代价：`|X|·C/word`（m=2 子集和）或 `|X|²`（小核 B&B）或递归预算。

### 6.2 子问题下界 `SUB-LB`

```text
函数 SUB-LB(X, d, B, a, qmin, A)
────────────────────────────────────────────────
1  if |X| ≤ k_exact:
2      return EXACT-SUB(X, a, A)       # 精确 T(X;σ)，附证明
3  T ← max( T_PACK(X,a,A), a+CP(X), a+ceil(W(X)/m) )
4  if m==2 and |X| ≤ k_bitset:
5      T ← max(T, a + C*(X))          # 精确装箱下界
6  T ← max(T, a + C*_DFF(X))          # m>2 / 大核心
7  if d>0 and B>0 and X⊂R:
8      T ← max(T, a + CORE-INDEX-SUB(X, d-1, B/2))
9  return T, π
```

- `EXACT-SUB(X,a,A)`：在 `G[X]` 上用带机器释放时间的小型 B&B/DFS 求精确 `T`，返回完整调度或精确值证书。
- `CORE-INDEX-SUB(X,d-1,·)`：在诱导子问题 `G[X]` 上运行同一套索引；它使用 `X` 内的静态 head/tail，返回 `OPT_X` 的下界。递归深度/预算递减。
- 第 7 行的 `X⊂R` 防止对全集合递归；全集合的 `C*`/DFF/CP 仍在第 3–6 行。

### 6.3 节点下界 `LB-X4`

```text
函数 LB-X4(σ, U, d, B_core)
────────────────────────────────────────────────
1  L ← max(C(σ), LB_CP(σ), LB_W(σ))
2  if L ≥ U: return L, ∅
3  L_CI, w1 ← CORE-INDEX(σ, 0, B_core/4)      # 闭式打包核，便宜
4  L ← max(L, L_CI)
5  if L ≥ U: return L, w1
6  L_P, w2 ← CORE-INDEX(σ, d, B_core)         # 优先核，递归
7  L ← max(L, L_P)
8  if L ≥ U: return L, w2
9  L_A, w3 ← AVAIL-INDEX(σ, B_core/2)         # A-aware 核
10 L ← max(L, L_A)
11 if L ≥ U: return L, w3
12 if gap_small(σ):
13     L_D, w4 ← DUAL-CERTIFY(σ, U-1, K_dual)
14     L ← max(L, L_D)
15 return L, argmax witness
```

`AVAIL-INDEX` 与 `CORE-INDEX` 结构相同，只是 `SUB-LB` 用 `T_PACK`/`EXACT-SUB(X,a,A)` 和 `B_A`。`L_D` 仍来自 v0.2 的时间价格对偶。

### 6.4 主循环

```text
算法 X-DUB/CI(G,p,m,B)
────────────────────────────────────────────────
1  (r,q,L0) ← PRECOMPUTE(G,p,m)
2  π0,U0 ← CP-LIST-SCHEDULE(G,p,m)
3  best ← (U0,π0); U ← U0
4  root ← NEW-NODE(σ0=(∅,0^m,⊥)); root.lb ← LB-X4(root,U,d0,B0)
5  F ← {root}; L ← max(L0,root.lb)
6  state ← INIT-CERT-STATE()
7  for t=1,2,...,B do
8      if F=∅ then L←U; break
9      if L≥U then break
10     if t mod K_t = 0 then
11         BBF-STEP(root,state)          # 证书侧：扩展 min-lb open 节点
12     else
13         MCTS-STEP(root)               # 上界侧：UCT + rollout
14     UPDATE-FRONTIER(root)
15     L ← max(L, MIN-LB(F))
16     if t mod T_scan = 0 then
17         L ← max(L, SCAN-INDEX(F,U,state))   # 对前沿节点跑 CORE-INDEX
18     ADAPT-UPDATE(state)
19 end for
20 if F=∅ or L≥U then PROOF ← BUILD-PROOF(root,U)
21 return best, L, U, gap=(U-L)/max(1,L), ρ=U/max(1,L), PROOF
```

`K_t` 沿用 v0.3 的间隙感知比例：

```text
K_t = clip( ceil( K_max · (U-L) / max(1,U) ), 1, K_max )
```

间隙大 → 多跑 MCTS 降 `U`；间隙小 → 多跑 B&B/证书升 `L`。

### 6.5 资源感知预算控制器

**候选层**：`CORE-INDEX` 用最大堆按

```text
priority(i,j) = (UB_CI(i,j)-L) / cost(R_{ij})
```

排序；先处理「可能提升大、求解便宜」的矩形。若 `UB≤L`，跳过。

**节点层**：证书侧维护前沿节点的潜力

```text
Pot(v) = max(0, L_cheap(v) - L_global)
Cost(v) = c0 + c1·|R(v)|²
```

优先扩展 `Pot/Cost` 高的节点；`L_cheap` 用 `CORE-INDEX` 的廉价层（DFF/CP/work/精确 C*）计算，不跑递归。

**深度/预算**：若某节点连续 `f` 次没有提升，则

```text
d ← min(d+1, d_max)
B_core ← min(2·B_core, B_core_max)
k_exact ← min(k_exact+2, k_exact_max)
```

一旦提升，回退到基准值。这个规则是启发式的，没有 regret 保证；正确性不依赖它。

**CORE vs DUAL**：沿用 v0.3 的 UCB/特征路由：

```text
UCB(a) = success_rate(a) + sqrt(2 ln(N+1)/n_a) - c_t·avg_time(a)
```

优先约束稀疏、`p_max/H` 大、`W/(mH)` 接近 1 → 先验偏向 CORE；优先约束密集、`p_max/H` 小、对偶价格有明显峰 → 先验偏向 DUAL。控制器只决定「先跑哪个见证器」，不直接剪枝。

### 6.6 角色分离

- **证书侧**：`CORE-INDEX`/`AVAIL-INDEX`/`DUAL` 负责 `L` 和最终最优性证明；不依赖 UCT 统计。
- **上界侧**：`DUB-MCTS` 只负责可行解和 `U`；不产生剪枝。
- **索引/控制器**：只决定候选顺序、递归深度、预算；不参与正确性证明。
- **证明树**：`CORE-INDEX` 的每个局部规则独立可检查；控制器状态不进证明。

## 7. 证明树与 checker

### 7.1 新节点

```text
CORE-INDEX: 附带 (i, j, X, T_LB, π, kind)
```

含义：`X=R_{ij}`，`a=lo_i`，`qmin=q_j`，`T_LB≤T(X;σ)`，因此

```text
B = a + qmin + T_LB
```

是 `OPT(σ)` 的合法下界。

`kind` 的取值：

- `PACK`：`T_LB=a+C`，`π` 证明 `BP(X,m,C)` 不可行（v0.3 的 `PACK-CORE` 是特例）。
- `DFF(k,C)`：`π` 证明 `Σ u_k(p_i;C)>m`；`T_LB=a+C+1`。
- `EXACT-SUB`：`π` 是 `G[X]` 在机器释放 `max(a,A_k)` 下的精确最优调度/值；`T_LB` 等于该值。
- `PREC-LB`：`π` 证明 `OPT_X≥T_LB-a`（CP/work/C*/递归 `CORE-INDEX` 子证明）。
- `AVAIL-PACK`：`π` 证明 `X` 在 `b=T_LB-1` 时无法装进容量 `max(0,b-max(a,A_k))` 的箱子。
- `RECURSIVE`：`π` 是 `CORE-INDEX-SUB` 在 `G[X]` 上的子证明，给出 `OPT_X≥T_LB-a`。

### 7.2 checker 规则

```text
CHECK-CORE-INDEX(σ, U, i, j, X, T_LB, π, kind):
1  重算 R, lo_i, q_i, A_k
2  验证 i,j∈R 且 lo_j≥lo_i, q_i≥q_j
3  计算 X' ← {k∈R: lo_k≥lo_i, q_k≥q_j}; 验证 X'=X
4  a ← lo_i; qm ← q_j
5  按 kind 验证 π:
6      PACK:       C=T_LB-a; 验证 BP(X,m,C) 不可行
7      DFF:        C=T_LB-a-1; 验证 Σ u_k(p_i;C)>m
8      EXACT-SUB:  验证 π 是 G[X] 在释放 max(a,A_k) 下的精确 T，且值=T_LB
9      PREC-LB:    验证 π 证明 OPT_X≥T_LB-a
10     AVAIL-PACK: b=T_LB-1; 验证 X 不能装入容量 max(0,b-max(a,A_k))
11     RECURSIVE:  递归 CHECK-CORE-INDEX 在 G[X] 上，得到 OPT_X≥T_LB-a
12 验证 B=a+qm+T_LB
13 接受：对任意 H≤B-1，X 被强制在窗口 [a,T_LB-1) 内，
    而 π 说明 X 在该资源环境下需要 ≥T_LB 的时间，矛盾。
```

- 第 13 行的论证是 §3–§5 的引理 1/3/5 的算术版本；checker 只需验证 `T_LB` 的子问题下界和强制条件。
- 对 `PACK`，窗口长度是 `C=T_LB-a`；对 `AVAIL-PACK`，窗口是 `[a,T_LB-1)`，容量在 `b=T_LB-1` 处计算。两类不要混淆。
- `EXACT-SUB` 的精确性由 v0.3 的 `EXACT-SMALL` 证明树或一个独立的小型 B&B 证书验证；checker 不信任搜索器的缓存。
- 其余节点 `TERMINAL/PRUNED-DUAL/EXACT/EXHAUSTED` 的规则不变。

### 7.3 证明树闭合

`BUILD-PROOF` 后序构建：

- `TERMINAL`：附完整可行调度，`Cmax≥U`。
- `PRUNED-DUAL`：附 `λ`，`g_H>0`。
- `CORE-INDEX`：附 `(i,j,X,T_LB,π,kind)`；若 `B≥U`，该节点关闭。
- `EXACT`：附精确子求解器的值/证书。
- `EXHAUSTED`：所有子节点关闭，动作集合被覆盖。

**定理 6（证明树可靠）**：若 `CHECK(root)` 通过，则 `U=OPT`。

**证明**：对树自底向上归纳。`CORE-INDEX` 由引理 1/3/5 没有 `Cmax≤B-1` 的完成，而 `B≥U`，所以没有 `Cmax<U` 的完成；`TERMINAL` 无更优完成；`PRUNED-DUAL` 由 v0.2 引理 1；`EXACT` 由精确子求解器；`EXHAUSTED` 覆盖所有动作。归纳到根，根没有 `Cmax<U` 的完成；incumbent 给出可行 `U`，故 `U=OPT`。证毕。

## 8. 正确性论证

### 8.1 可采纳性

**引理 1（核心阈值）**：已证于 §3.1。  
**引理 3（优先核）**：已证于 §4.1。  
**引理 5（可用时间核）**：已证于 §5.1。  
**引理 7（一般核）**：若 `T_LB≤T`，则 `T_LB+qmin` 可采纳；证明同引理 5。  
**定理 7（组合下界）**：

```text
L_X4(σ) = max(L0(σ), L_D(σ), L_CI(σ), L_P(σ), L_A(σ), L_G(σ)) ≤ OPT(σ).
```

**证明**：每个分量分别是 `OPT(σ)` 的下界（引理 1/3/5/7 与 v0.2 对偶引理）；有限个下界的 max 仍是下界。证毕。

### 8.2 有证书竞争比

**定义**：给定状态 `σ`、可行 incumbent `U`、下界 `L=L_X4(σ)`，定义

```text
ρ(σ) = U / max(1,L).
```

**定理 8（竞争比证书）**：若 `L>0`，则 `U/OPT(σ)≤ρ(σ)`；若 `ρ=1`，则 `U=OPT(σ)`。若 `L=0`，剩余集为空且 `U=C(σ)`，定义 `ρ=1`。

**证明**：`L≤OPT≤U`，所以 `U/OPT≤U/L=ρ`。若 `ρ=1`，则 `U=L≤OPT≤U`，故 `OPT=U`。证毕。

> 这不是对 `P|prec|Cmax` 的新最坏情况近似比；Graham 的 `2-1/m` 仍是 `U0` 的保证。`ρ` 是算法能写进证书的 incumbent 竞争比上界，用来驱动 anytime 预算：`ρ` 大时优先升 `L`，`ρ` 小时优先降 `U`。

### 8.3 索引的搜索竞争比

**定义**：设 `F` 是一个核心族（PACK/PREC/AVAIL/GENERAL），`L_F^*` 是理想族下界，`L_F^alg` 是索引实际返回的下界。定义搜索竞争比

```text
CR_search(F) = (L_F^* - L0 + 1) / (L_F^alg - L0 + 1)  ≥ 1.
```

**定理 9（m=2 打包核无搜索损失）**：若 `C*(X)` 精确、所有合法 pair 都被枚举，则 `L_CI=L_PC^*`，`CR_search(PACK)=1`。

**证明**：定理 1 的逐点等价。证毕。

**定理 10（优先/可用时间核的预算化）**：若 `SUB-LB` 的每个分量都是 `OPT_X`/`T` 的下界，则 `L_P^alg≤L_P^*`、`L_G^alg≤L_G^*`；`CR_search≥1`。若 `|X|≤k_exact` 的候选都精确，且最优核心落在这些候选上，则 `CR_search=1` 对该核心成立。

**证明**：逐点下界与支配矩形。证毕。

### 8.4 任意时刻区间与终止

**定理 11（anytime 区间）**：在 `X-DUB/CI` 运行的任意时刻，`L≤OPT≤U`。

**证明**：`U` 来自可行调度（CP 或 rollout），故 `OPT≤U`。`L` 是 `L0`、前沿 `LB-X4`、`SCAN-INDEX` 的 max；每个分量由定理 7 可采纳，前沿覆盖性（v0.3 引理 2）给出 `L≤OPT`。证毕。

**定理 12（精确模式终止）**：若 `X-EXACT` 因 `F=∅` 或 `L≥U` 终止，则 `U=OPT`。

**证明**：同 v0.3 定理 6；把 `LB-X3` 换成 `LB-X4`，可采纳性由定理 7 保证。若存在 `Cmax<U` 的调度，由动作覆盖性和前沿覆盖性，它必须经过某个 open 节点 `v` 且 `LB-X4(v)≤Cmax<U`，与 `F=∅` 或 `L≥U` 矛盾。证毕。

**定理 13（有限完备性）**：搜索树有限；`X-EXACT` 每次分支前进一个任务；`EXACT-SMALL`/`EXACT-SUB` 在有限核心上精确；剪枝只删除不可能优于 `U` 的子树。预算无限且 `k_exact` 足够覆盖最优核心时，`X-EXACT` 最终关闭根并返回 `OPT`。最坏情况时间复杂度指数；这是 NP-hard 问题的预期行为。

## 9. 复杂度分析

### 9.1 单节点

- **预处理**：拓扑排序 + head/tail，`O(n+|E|)`。
- **合法 pair**：`O(n²)`；bitset 交集 `O(n³/word)`，二维前缀和聚合 `O(n²)`。
- **候选去重/预筛**：`O(n²)` 次哈希/比较；`UB≤L` 的候选不进入精确层。
- **m=2 `C*(X)`**：bitset `O(|X|·C_max/word)`；MITM `O(2^{|X|/2})`。
- **m=2 `T_PACK`**：二分 `O(log U)` 次，每次 `O(|X|·C/word)`，总 `O(|X|·C/word·log U)`。
- **精确 `EXACT-SUB`**：最坏 `O(m^{|X|})`；只在 `|X|≤k_exact` 时调用。
- **递归 `CORE-INDEX-SUB`**：每层 `O(|X|²)` 个 pair，深度 `d`；最坏 `O((n²)^d)`，由 `d_max`/`B_core` 截断。
- **对偶**：`K_dual` 次最小割；`T_cut(n,H)` 同 v0.2。
- **MCTS rollout**：`O(n(n+|E|))`。

### 9.2 总计

设 `N` 为 B&B 物化节点数，`B` 为总预算，`T_pair` 为单候选求值代价：

```text
时间: O( N·(n²·T_pair + T_dual + b(n+m)) + B·n(n+|E|) )
空间: O( N(n+m) + n² + B_core )        # n² 为索引网格，B_core 为子问题缓存
```

最坏情况：

```text
N = O((m·n)^n)
T_pair = O(m^{k_exact}) 或 O(n²·T_pair(d-1)) 递归
```

- **认证总时间仍最坏指数**；v0.4 没有改变 `P|prec|Cmax` 的最坏复杂度。
- **索引的收益**是去掉 H 循环：v0.3 的 `L_PC` 若扫描 `U-L0` 个 H，每个 H 枚举 `O(n²)` 窗口，则最坏 `O(n²·U·T_C)`；v0.4 的打包核是 `O(n²·T_C)`。
- **递归核的代价**是新的指数/伪多项式维度，由 `k_exact,d_max,B_core` 控制。
- **证明检查**：`O(n+|E|)` 重算 lo/q/A，加每个 `CORE-INDEX` 节点的局部检查；子证明递归。证书大小 `O(k + Σ 子证明)`，其中 `k` 是获胜核心规模，不是候选总数。

### 9.3 成本控制

- 廉价层优先：`CP/work/DFF/C*` 先跑；只有 `UB>L` 的候选进入精确层。
- `k_exact` 默认 8–12；`d_max` 默认 2–3；`B_core` 按失败加倍。
- 候选按 `(UB-L)/cost` 排序；节点按 `Pot/Cost` 排序。
- 子问题结果按 `(X,d)` 缓存；同一核心在多个 pair 上复用。
- 只对 `X⊂R` 递归；全集合用 `LB_0`，避免循环。
- 若 `m>2` 且精确装箱太贵，退回 DFF/对偶；证明树只接受可检查的下界证据。

## 10. 实验设计与本轮结果

### 10.1 6 任务反例

```text
m=2, p=(10,8,7,3,2,2), E=∅
```

结果：

```text
L0 = 16
L_CI = 17 = OPT
witness: i=j=0, X=V, a=0, qmin=0, C*(V)=17
```

检查：`BP(V,2,16)` 不可行（无子集和 16），`BP(V,2,17)` 可行（`10+3+2+2=17`，`8+7=15`）。支配矩形取全集合；索引一步得到 17。

### 10.2 90 个小实例（本轮新种子）

**设置**：`m=2`；30 随机 DAG（`n∈{5,6,7}`，边概率 0.3，`p_i∈[1,6]`），30 无依赖（`n∈{5,6,7}`，`p_i∈[2,9]`），30 两层 DAG（`n∈{6,7}`，前半到后半边概率 0.5，`p_i∈[1,7]`）。OPT 由精确 DFS 求出。`L_P` 对 proper 子集用精确 `OPT_X`（`|X|≤6`），全集合用 `max(CP/work,C*)`。

|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 随机 DAG | 30 | 25 | 29 | 29 | 4 | 0 | 7 | 1 | 1 | 1.295 |
| 无依赖 | 30 | 27 | 30 | 30 | 3 | 0 | 3 | 0 | 0 | 1.385 |

1. 索引把总间隙从 15 降到 1，和 v0.3 的打包核在同一水平；但这里是**一次索引直接求出**，不需要 H/窗口扫描。
2. 在这批小实例上 `L_P` 没有额外改进（0/90）；剩余间隙来自全集合或非 proper 子集，proper 优先核没有机会发挥。
3. 这张表与 v0.3 的 90 实例表不是同一批随机种子，不能逐项比较；它的作用是验证索引/优先核的实现与安全性。

### 10.3 180 个 n=7 稠密 DAG

**设置**：`n=7, m=2`；边概率 `0.3/0.5/0.7`，每档 60 个；`p_i∈[1,8]`；OPT 由精确 DFS。`L_P` 对 proper 子集（`|X|≤6`）精确求 `OPT_X`，全集合用 `max(CP/work,C*)`。

| **合计** | **180** | **163** | **175** | **178** | **3** |

### 10.4 内部状态：A-aware 核

**设置**：`n=6, m=2`，随机 DAG（边概率 0.3），随机调度 35% 的任务得到可达状态；共 120 个状态。OPT 由状态级精确 DFS 求出。

| 方法 | 合法（≤OPT） | =OPT | 严格高于统一容量 | 平均提升 |
|---|---:|---:|---:|---:|
| `L_CI`（统一容量） | 120/120 | — | — | — |
| `L_A`（A-aware） | 120/120 | 117/120 | 42/120 | 2.5 |

**另一个 100 状态样本**（`n=6, m=2`，随机 DAG）：`L_A` 与「A-aware + precedence」的一般核 `L_G` 相同（0/100 额外改进）；`L_A=OPT` 93/100；平均 `L_A=13.03`，平均 OPT=13.11。说明状态层的主要收益来自 `A_k`，而 §4 的优先核收益主要在根节点/浅层 proper 核心。

**手算状态例子**见 §5.3：`L0=L_CI=12`，`L_A=18=OPT`。

### 10.5 等价性、支配性与合法性对拍

- **6 任务全子集**：63/63 个子集满足支配矩形引理；`L_CI=17=OPT`。
- **根实例**：50/50 个随机 `n=6` 实例上，`L_CI` 与穷尽窗口扫描（含 `L0`）相等。
- **内部状态**：80/80 个状态上，`L_CI` 与统一容量穷尽扫描相等；`L_A` 与 A-aware 穷尽扫描相等（修复了 `C(σ)` 后）。
- **合法性**：90 + 180 个根实例、120 + 100 个状态，共 490 个实例/状态上，`L0/L_CI/L_P/L_A` 均未超过 OPT（0 次违规）。
- **原型速度**（仅 sanity check，不是 benchmark）：50 个 `n=6` 根实例上，索引约 0.0048s，窗口扫描约 0.0205s（约 4.3×）；80 个状态上 `L_CI` 约 0.004s、`L_A` 约 0.012s，对应穷尽扫描约 0.015s/0.018s。

### 10.6 下一轮实验协议

**P1（checker 对拍）**

- 500 个 `n≤9, m∈{2,3}` 随机 DAG/无依赖/分层实例；
- 独立实现 `CHECK-CORE-INDEX`，重算 `lo/q/A`、支配矩形、`C*`/DFF/`EXACT-SUB` 证据；
- 目标：零假证书、零错误剪枝；checker 与主算法实现隔离。

**P2（核 vs 完整对偶）**

- `n=10..20, m=2..4`，随机 DAG、fork-join、partition、单长链+多短任务；
- 实现 v0.2 的 min-cut 对偶 + 次梯度/割平面；
- 比较 `L0,L_ER,L_DFF,L_CI,L_P,L_A,L_D,max` 的根界；
- 专门搜索 `L_D>L_P` 和 `L_P>L_D` 的实例，验证两个证书族不可比较/互补；
- 指标：根间隙、单次证书时间、证书大小、闭合率。

**P3（索引消融）**

- 穷尽 pair vs 束搜索 vs 随机 pair；
- `C*` 精确 vs DFF vs MITM；
- `k_exact∈{6,8,10,12}`、`d_max∈{0,1,2,3}`、`B_core`；
- 指标：找到强核的比例、核心大小、精确子问题调用次数、总时间。

**P4（规模/难例）**

- `n=20..100, m=2,4,8`，预算 1s/10s/60s；
- PSPLIB 风格、fork-join、强资源竞争、partition；
- 与 CP、DUB-MCTS、X-DUB、X-DUB/PC、CP-SAT/SCIP 对照；
- 指标：incumbent gap、`[L,U]`、证书率、anytime 曲线、峰值内存、checker 时间。

**P5（A-aware/优先核消融）**

- 根 vs 内部状态；`A_k=0` vs 随机释放；
- `L_CI` vs `L_P` vs `L_A` vs `L_G`；
- 目标：确认优先核的收益是否只在根/浅层，A-aware 是否只在内部状态；如果两者在多数实例上不互补，就按特征路由而不是全开。

**P6（扩展）**

- m>2 的精确 `C*`/`T`；
- 随机工时/释放时间；
- 带准备时间、批处理、异构机器的扩展；
- 证明树 checker 的独立实现与 fuzz。

**判定标准**：如果优先核在 n≥20 或 PSPLIB 上不能稳定超过 `L_CI`，或者索引/递归开销使总时间显著变慢，那么 v0.4 的核心假设（优先核值得递归求解）就被证伪；应把 `L_P` 降级为根节点/小核心的专用证书，主下界仍用 `L_CI`/对偶。

## 11. 已知风险

1. **递归核心的指数/伪多项式成本**：`OPT_X`/`T(X;σ)` 是 NP-hard；`O(n²)` 候选 × 递归子问题求解可能使每次下界计算比 v0.3 贵一个数量级。`k_exact,d_max,B_core` 是必需的刹车。
2. **索引本身的 O(n²) 成本**：大 n 时，即使只建 pair/矩形索引也可能很贵；二维前缀和、bitset 和缓存能降常数，但没有改变最坏 `O(n²)`。需要增量维护/剪枝，否则 B&B 节点一多就拖慢。
3. **证明树变深**：`CORE-INDEX` 可以递归到子问题，证明大小/检查时间随深度增长；一个深的 `RECURSIVE` 节点可能比 v0.3 的单个 `PACK-CORE` 难检查得多。
4. **m>2 的精确性缺口**：`C*(X)`/`OPT_X` 在 m>2 时没有 m=2 的子集和精确判据；DFF/小核 B&B 可能弱或爆炸。本轮的严格改进全部是 m=2。
5. **全集合循环**：`X=R` 时不能用精确 `OPT_R`（否则就是解原问题）；我们用 `LB_0(R)` 兜底。如果最优核心就是全集合，`L_P` 可能不如预期；§10.2 的 90 实例剩余间隙就是这种情况的候选。
6. **优先核的经验范围窄**：3/180 的严格改进来自 n=7、稠密随机 DAG；90 个小实例上 0 改进。收益可能集中在特定结构（小核心、内部优先冲突），不能外推到 PSPLIB/大规模。
7. **A-aware 的精确性只在 m=2**：异构装箱阈值 `b*` 用二分+子集和精确；m>2 只能用小核 B&B/DFF，可能弱。且 `T(X;σ)` 的精确求解带释放时间，比纯装箱更难。
8. **部分重叠/跨窗口冲突仍看不见**：核心索引仍然用一个窗口/一个子问题；多个窗口的部分重叠、流式资源冲突（v0.3 对偶/RA 流证书能看见的）不在 `CORE-INDEX` 里。它是对偶/流的补充，不是替代。
9. **单调性假设**：支配矩形对 `LB_d` 的化简要求子问题下界对超集单调；标准松弛（OPT/CP/work/C*/DFF）满足，但某些启发式/缓存近似可能不满足。不满足时只损失强度，不损失正确性，但理论上的「O(n²) 足够」不再成立。
10. **竞争比是保守的**：`ρ=U/L` 是 `U/OPT` 的上界，但可能远大于真实竞争比；它不是经典 worst-case competitive ratio，也不构成新的近似算法。论文表述必须避免过度声明。
11. **checker 工程复杂度**：`CORE-INDEX` 有 6 种 `kind`，每种都要独立验证；一个错误的 `T_LB` 或窗口长度会把假下界当成真证书。需要独立实现、对抗测试、默认只用 `PACK/DFF`。
12. **实验规模小**：`n≤7, m=2`，随机生成；490 个实例/状态的 0 违规是 sanity check，不是可扩展性证明。原型速度数字很小，不能当 benchmark。
13. **模型假设**：确定性、同构机器、整数工时、无 release/准备时间；A-aware 只处理机器可用时间 `A_k`，不处理未来预留/主动空闲。

---

## 12. 一句话最大风险

**当前方案最大的风险是：递归核心索引把下界强度押在「找到并精确求解一个小核心」上，而 O(n²) 候选枚举加递归子问题求解可能让每次下界计算比 v0.3 贵一个数量级；在大型或 m>2 的实例上，它可能既找不到足够强的核心，又因为索引/递归开销拖慢 B&B。**
