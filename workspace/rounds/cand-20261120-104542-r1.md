# 第 1 轮（UniBot 线 · 本轮灵感：「动态避障」×「步态规划」）

> **继承声明**：本文件沿用上一版已核实的一手事实与来源（检索日期 2026-11-17），**不新增未经核实的外部断言**。上一版的 U1–U12 / L1–L7 / E601–E618 保留为地基；本轮新增 U13–U24 / L8–L14 / E619–E630。上一版的核心判断（终态成功是唯一计分货币；断点在最后一环；单自由度夹爪使抓握成为隐变量）不变，本轮只回答一个新问题：**如何让最后一环在动态环境里，不被一次盲目的动作块赌死。**

## 0. 一句话路线

上一版把桌面操作建模为「隐变量抓握 + 技能路由 + chunk 工程」；本轮把两个新灵感编译成同一个问题的两面：**桌面操作不是一条开环动作序列，而是一场在接触相序上的「准静态步态」；动态避障不是绕开一个静态障碍，而是让每一步的「落脚点」（抓取 / 放置 / 插入姿态）在动作块执行期间始终处在一个可证明的安全包络内。** 于是本轮主线是 **UniBot-STRIDE**：用**接触相序混合自动机**（步态规划的形式）管住「何时换相、何时退回」，用**动态安全包络 + 承诺时域**（动态避障的形式）管住「这一块动作还能不能继续执行」。

## 1. 直觉解释（先直觉，后形式化）

### 1.1 「动态避障」：真正要避的不是障碍，而是「动作块的盲目承诺」

**直觉**：人在桌面上做精细操作时，眼睛和手是持续耦合的——快碰到杯子就减速，看到有人伸手就停一下，发现物体被带歪就松手重抓。当前的 chunked VLA 不是这样：它一次输出 8–16 步动作，然后在这段时间里「闭眼执行」。在静态、干净、无人的桌面上，这个开环承诺问题不大；但在 UniBot 的 5 类泛化场景里，尤其是「人为干扰」和「干扰物」两类，环境在动作块执行期间会变。**此时失败不是「规划错了」，而是「承诺太长了」。**

所以「动态避障」的第一性原理不是「检测障碍物并绕开」，而是：

1. **障碍是移动的 / 会出现的**：人手、被碰倒的物体、机器人自己的另一只手臂、被抓起的物体本身（payload 改变了机器人的扫掠体积）；
2. **策略必须现在动作、以后才知道**：这是一个「承诺 vs 反应」的权衡；
3. **安全是一个时域性质**：不是当前帧不碰，而是「未来 T 步内都不碰」；因此需要**动作块级的安全包络**，而不是逐帧碰撞检查。

**形式化草图**：给定动作块 `a_{1:T}`、当前状态 `x_t`、障碍预测 `F_{t:t+T}`，计算机器人（含 payload）的可达扫掠集 `O^+_{t:t+T}`；若 `O^+ ∩ F^+ = ∅`，该块被认证为安全，可以执行；否则只执行到认证失效前的最后一步 `T_c`，然后重新规划。`T_c` 就是**承诺时域**——桌面操作的「步幅」。

### 1.2 「步态规划」：桌面任务是一场接触相序上的准静态步态

**直觉**：走路的核心不是「腿怎么摆」，而是**接触相序**：哪只脚支撑、哪只脚摆动、何时换脚、失去平衡时如何补一步。把这个形式搬到桌面操作，立刻得到一套更精确的语言：

- **支撑相 / 摆动相** ↔ **接触相 / 自由相**：抓稳物体时是「支撑」，空手接近时是「摆动」；
- **落脚点** ↔ **抓取 / 放置 / 插入的接触姿态**：不是连续轨迹上的一个点，而是一个离散的、必须满足几何与稳定性约束的「接触配置」；
- **ZMP / 捕获点 / 稳定裕度** ↔ **接触稳定裕度**：抓握会不会滑、插入时会不会卡死、放置时会不会倒；
- **换脚与恢复步** ↔ **重抓、退让、换手、改用非抓取原语**；
- **步态相位机（事件触发）** ↔ **接触相序混合自动机**：用 guard（抓稳、滑移、对齐误差、碰撞风险）触发相位切换，而不是用固定步数硬切。

关键的经验支撑（本轮零成本探针，见 §2）：官方状态序列里**下肢几乎不动**（下肢关节方差中位数仅为手臂的 1/5573），所以不要把「步态规划」误读成「让 G1 走到桌边」。真正的「步态」在**末端接触相序**里；腿式行走不在数据分布内，硬做会 OOD。这个判断直接修剪了上一版 IP-05 的过度投入。

### 1.3 合成：STRIDE = 接触相序（步态）× 安全包络（避障）× 稳定裕度（平衡）× 恢复步（失败恢复）

- **接触相序混合自动机（CSHA）**：把上一版的 `z_phase` 从「分类器输出的 token」升级为「带 guard / invariant / reset 的混合自动机状态」；抓握不再是二值判定，而是「grasp 模式 + 稳定裕度 + 滑移 guard」。
- **动态安全包络（DynaGuard）**：在动作块级别做保守可达集与障碍集的交检查，输出可执行的承诺时域 `T_c`；环境变化或跟踪误差超界时事件触发中断。
- **接触稳定裕度（SlipMargin）**：把「抓住没有」升级为「还能抓多久」；用 1 维夹爪 + 腕部视觉 + EE 加速度估一个保守下界，触发「恢复步」。
- **恢复步库（RecoveryGait）**：重抓 / 退让 / 换手 / 旋转腕 / 非抓取原语；带最大重试次数与「继续 vs 恢复」的期望收益比较。
- **承诺时域调度（CommitHorizon）**：`T_c` 随相位与拥挤度自适应；接近 / 抓取 / 对齐用短承诺，搬运 / 放置用长承诺。

## 2. 本轮的两个零成本探针（不依赖真机，不新增外部事实）

### 探针 A：官方状态序列的「步态」在哪里？

数据：`exp/unibot_states/G1_Dex1_*.npz`，12 个任务 × 800 帧（contig 切分）。只读状态，不做任何训练。

- 手臂关节方差中位数 **0.140**；下肢关节方差中位数 **2.52e-5**；**比值约 5573×** ⇒ 官方操作数据里下肢基本静止，「腿式步态」不在分布内。
- 双臂末端合成位移范围中位数 **0.702 m** ⇒ 任务的运动量几乎全在手臂。
- 夹爪行程：部分任务单臂夹爪几乎不动（HangCup 左 1.2e-4；ConveyorSorting 右 6.1e-5）⇒ 单臂 / 双臂是任务相关变量，不能假设双手总在协同。
- 末端速度方向反转间隔：中位数 **5–6 帧**，p95 约 **30–32 帧**（按 30 fps 折算约 0.17–0.20 s / 1.0–1.07 s）⇒ **8 步 chunk（≈0.27 s）已接近中位反转间隔，16 步（≈0.53 s）明显超出**；固定长 chunk 会跨过多次方向反转，这是「承诺过长」的直接经验迹象（启发式探针，需真机确认）。
- 轨迹直线度（净位移 / 路径长度）中位数约 **0.08** ⇒ 运动高度往复，进一步支持「短承诺 + 事件触发」。

### 探针 B：接触密集型任务是否真的更难？

数据：`exp/r16_leaderboard_data.json`（8 模型 × 32 任务，teaser 占位表；沿用上一版口径）。

- 把 12 个接触密集 / 动态任务（Disconnect Ethernet、Plug Charger、Pick Out Battery、Unlock、Open Pill Bottle、Fold Towel、Zip Up、Conveyor Food Sorting、Plug In Ethernet、Remove Pinned Note、Syringe Water Transfer、Spell robot）与其余 20 个准静态抓放任务对比：平均成功率 **23.88 vs 25.95（−2.07，−8.0%）**。
- 但 per-task oracle 上界几乎相同（**+8.97 vs +8.67**）⇒ **接触密集任务的困难不是「模型分歧更大」这么简单，而是整体更难；单靠技能路由补不回来，必须有机制层的改进。** 这正好支持本轮把火力从「路由」转向「相序 + 安全 + 恢复」。
- 复算上一版结论：oracle **33.96** vs 最好单模型 **29.70（+4.26）**；top-2 **32.22（+2.52）**；Kendall τ 均值 **0.064**（28 对里仅 1 对 |τ|>0.2）。跨模型分歧（spread）与 oracle gap 的相关为 **0.873** ⇒ spread 可作路由红利的廉价代理；任务均值与 spread 弱负相关（**r=−0.19**）⇒ 越难的任务分歧略大，但不足以单独解释接触密集任务的劣势。

**探针的结论（可执行）**：

- **T4 不要做腿式步态**：下肢不在数据分布内；「步态」只取接触相序的形式，不取行走的实现。
- **T5 承诺过长是结构性风险**：方向反转间隔与固定 chunk 长度同量级，说明「一块到底」会跨过多次需要反应的事件。
- **T6 接触密集任务是机制瓶颈**：它们整体更难且路由上界不更大 ⇒ 需要「相序 + 稳定裕度 + 恢复」，而不是更多专家。

## 4. 研究问题（本轮版）

- **Q1（相序可辨识性）**：在只有 1 维夹爪、EE 位姿、腕部视觉的条件下，能否把接触相序（reach / grasp / lift / transport / align / insert / place / release / recover）辨识成带 guard 的混合自动机，并让 guard 的误触发率低到不伤害基线？
- **Q2（安全包络的可计算性）**：在 per-step 延迟预算内，能否用 4 路相机 + 本体感觉算出保守但不过度保守的动作块安全包络？包络的假阳性会不会把「能过的窄缝」误判为不可过，导致冻结 / 抖动？
- **Q3（承诺时域的最优性）**：是否存在相位 / 拥挤度相关的 `T_c`，使「碰撞风险 × 超时风险」的加权和最小？固定 8/16 步与自适应 `T_c` 的差距有多大？
- **Q4（稳定裕度的可观测性）**：1 维夹爪 + 无触觉下，滑移裕度只能部分观测；保守下界是否足够触发「恢复步」，还是会漏掉大多数滑移？
- **Q5（恢复步的净收益）**：重抓 / 退让 / 换手 / 非抓取原语在什么条件下严格优于「继续执行」？最大重试次数如何定，才能避免把可救失败变成超时？
- **Q6（接口语义与合规）**：评测端是否允许逐次改变返回的 chunk 长度？事件触发中断会不会被「动作统计规律性 / 可信度」审核视为异常交互？安全证书如何自证？

## 5. 设计原则（在上一版 P1–P6 上新增）

- **P7 安全包络只做减法**：DynaGuard 只能缩小可执行动作集（截短 / 暂停 / 退让），不能注入任务特定的硬编码动作；所有安全决策可审计、可回放。
- **P8 事件触发优先于固定步数**：相序切换由 guard 触发，不由 chunk 边界触发；但每次触发必须有最小驻留时间，防止抖动。
- **P9 恢复步必须有正期望**：只有当「恢复的估计成功率 > 继续执行的估计成功率」时才恢复；否则继续，避免「越救越糟」。
- **P10 不在数据分布外硬做**：下肢 / 腿式步态、跨 episode 在线更新等低证据 / 高合规风险的动作，一律先做零成本探针，再决定是否投入。

## 6. 最小可提交闭环（MVP）与退化链

**MVP = IP-09（CSHA）+ IP-10（SlipMargin）+ IP-11（DynaGuard）+ IP-12（CommitHorizon）+ IP-14（InterferenceBench）+ 通用 VLA 基线**。
IP-13（RecoveryGait）先做最小版（重抓 + 退让两种），IP-15（StanceProbe）只做零成本探测。

**退化链**：

- Level-0 DynaGuard 不可用 / 假阳性过高 ⇒ 退回固定 chunk（原策略）；
- Level-1 SlipMargin 不可用 ⇒ 退回上一版 IP-02 的二值抓握确认；
- Level-2 CSHA 不可用（guard 误触发）⇒ 退回静态相位 token；
- Level-3 RecoveryGait 不可用 ⇒ 中止当前块并从当前状态重新规划；
- Level-4 全部不可用 ⇒ 退回纯基线策略（永远保留一个能跑通、可信度合规的安全网）。

## 7. 预期贡献（可验收）

1. **把桌面操作形式化为接触相序混合自动机**：给出 guard / invariant / reset 的明确定义，把「步态规划」从腿式行走迁移到接触相序，并用零成本探针证明下肢不在数据分布内（避免整条线走偏）。
2. **给出动作块级动态安全包络与承诺时域**：把「chunk 的盲目承诺」变成「可认证的承诺长度」，直接对齐 UniBot 的「人为干扰 / 干扰物」泛化轴。
3. **给出 1 维夹爪下的接触稳定裕度与滑移恢复**：把「抓住没有」升级为「还能抓多久」，并给出保守下界的可观测性分析。
4. **给出恢复步的净收益判据**：不是「失败就重试」，而是「恢复的期望成功率 > 继续执行的期望成功率」才重试，附最大重试次数与超时预算。
5. **一套可复用的安全 / 干扰代理评测**：在上一版六因子上加 `avoid` / `recover`，并给出接触密集子集的量化基线（23.88 vs 25.95）。
6. **可审计的安全证书**：每次截短 / 中断 / 恢复都留下可回放记录，主动对齐官方的可信度口径。

## 8. 本轮最大风险

**一句话**：本轮把赌注押在「安全包络 + 事件触发」上，而**安全包络的保守性会在窄缝 / 近接触相位制造「冻结—抖动—超时」的新失败模式**——越是需要精细插入的地方，包络越保守、越容易反复中止；由于榜单没有速度红利、只有超时惩罚，这种「过度谨慎」可能把本来能靠一次果断插入成功的回合，变成永远不敢插入的回合。

## 9. 下一轮迭代计划（深化与修剪，不推倒重来）

- **深化**：用共形预测 / 可达集学习把安全包络从「几何保守」变成「校准保守」；把 guard 的阈值做成 episode 内自校准；把 `T_c` 与上一版 IP-01 的相位专家对齐。
- **修剪预案**：若 DynaGuard 的假阳性导致超时率上升 >2%，则**只保留「事件触发中断」而不保留「预认证截短」**（即：默认执行完整 chunk，只在观测到环境变化时中断）；若 SlipMargin 的 AUROC <0.7，则退回二值抓握 + 固定重试。
- **保留项**：IP-09（相序形式化）、IP-11（安全包络）、IP-14（代理评测）三项不砍；它们是本轮的信息价值与机制正确性来源。

## 0. 本轮结论摘要

**一句话路线**：把上一版的「隐变量抓握 + 技能路由 + chunk 工程」升级为 **接触相序（步态）× 安全包络（动态避障）× 稳定裕度（平衡）× 恢复步（失败恢复）** 的四件套：

**CSHA（接触相序混合自动机）→ SlipMargin（滑移裕度）→ DynaGuard（动作块安全包络）→ CommitHorizon（承诺时域）→ RecoveryGait（恢复步）**，
外层仍是单 checkpoint、单 API、可审计的工程壳。

**为什么是这个组合（本轮量化依据）**：

| 证据 | 数值 | 推出的设计 |
|---|---|---|
| 12 个接触密集 / 动态任务 vs 20 个准静态抓放任务 | 平均成功率 **23.88 vs 25.95（−2.07，−8.0%）** | 接触密集任务是整体更难，不是单纯模型分歧 → 机制层改进（IP-09/10/11/13） |
| 接触密集 vs 准静态的 per-task oracle 上界 | **+8.97 vs +8.67**（几乎相同） | 路由红利不能解释接触密集劣势 → 不能只加专家，必须加相序与恢复 |
| 官方状态探针：手臂 / 下肢关节方差中位数 | **0.140 / 2.52e-5，比值 5573×** | 下肢几乎静止 ⇒ **不做腿式步态**；「步态」只取接触相序形式（IP-09） |
| 末端速度方向反转间隔中位数 / p95 | **5–6 帧 / 30–32 帧**（30 fps 下约 0.17–0.20 s / 1.0–1.07 s） | 8 步 chunk 已接近中位反转间隔，16 步明显超出 ⇒ 固定长 chunk 会跨过需反应的事件（IP-12） |
| 轨迹直线度（净位移 / 路径长度）中位数 | **0.08** | 运动高度往复 ⇒ 短承诺 + 事件触发优于一块到底（IP-11/12） |
| 跨模型 spread 与 oracle gap 的相关 | **r=0.873** | spread 可作路由红利的廉价代理；但接触密集任务不能只靠它（保留 IP-01，不扩投） |
| 任务均值与 spread 的相关 | **r=−0.19** | 越难的任务分歧略大，但不足以单独解释接触密集任务的劣势 |

**合规红线（沿用 P5 + 新增 P7）**：单一 checkpoint、单一 API；DynaGuard 只做「缩小动作集」的运行时安全过滤，不注入任务特定硬编码；不读评测侧私有信息；所有截短 / 中断 / 恢复写入可审计安全证书，避免被「动作统计规律性 / 可信度」审核误判为异常交互。

## 2. 创新点详述

### IP-09 · CSHA 接触相序混合自动机（P0）

- **动机**：上一版把 `z_phase` 当作一个分类器输出的 token，相位之间没有「能否切换」的约束，也没有「切换失败怎么办」。但桌面操作的失败恰恰发生在相序边界：还没抓稳就抬、还没对齐就插、滑移了却继续搬。步态规划的核心形式是**混合自动机**：离散模式 + 连续流 + guard / invariant / reset。把它迁移到接触相序，就能把「何时换相」从黑盒分类变成可验证的规则。
- **与现有方案的差异**：现有 VLA 多为「单段连续策略 + 固定 chunk」；少数分层方法有阶段分类器，但没有 guard 的充分性检查与 reset 语义。CSHA 把阶段分类器降级为「guard 的一个观测函数」，并显式定义每个模式的 invariant（例如 transport 期间必须 `m_t ≥ m_min`）与 reset（滑移 → 回 grasp / reach）。
- **技术可行性**：高。①相位标签可用上一版 IP-06 的 VLM + 规则伪标；②guard 的阈值可先用分位数 + 人工抽检；③自动机本身是 O(1) 状态机，推理开销可忽略。
- **所需资源**：数据 = 官方 32 数据集（复用上一版管线）；算力 = 小（guard 校准 + 状态机）；接口 = 无新增字段（仍是 `get_action`）。
- **落地步骤**：①定义 10 个模式与 6 类 guard（见 U13–U15）；②用官方数据伪标相序，人工抽检 5%；③实现自动机 + 最小驻留时间；④离线回放校准 guard 阈值；⑤真机 A/B：CSHA vs 静态 phase token；⑥消融每个 guard 的边际贡献。
- **风险**：①guard 误触发 → 抖动；缓解：最小驻留 + 置信度门控 + 只在连续 k 帧满足时切换。②模式划分过细 → 数据稀疏；缓解：先合并为 6 个粗模式（reach / grasp / transport / align / insert / release），再按需细分。③伪标噪声 → guard 学到标注器偏差；缓解：双标注器一致性 + 规则交叉验证。

### IP-10 · SlipMargin 接触稳定裕度（P0）

- **动机**：上一版的抓握确认是二值（抓住 / 没抓住），但真正的失败是「抓住之后滑了」。1 维夹爪没有触觉，滑移只能从三路信号间接推断：夹爪闭合速率、EE 加速度 / 抖动、腕部视觉中物体相对夹爪的位移。把「抓住没有」升级为「还能抓多久」，才能触发及时的恢复步。
- **与现有方案的差异**：现有方案要么不管滑移，要么只在失败后重试；SlipMargin 给出一个**连续的、带保守下界的稳定裕度**，并把恢复步的触发从「失败后」提前到「滑移前」。
- **技术可行性**：中。滑移的间接标签可从数据里造：夹爪闭合后物体相对腕部位移超阈值、或 EE 加速度与物体位移不一致；但 1 维夹爪下可观测性有限，必须承认只能估保守下界。
- **所需资源**：数据 = 官方数据（腕部帧 + 夹爪 + EE）；算力 = 单卡数小时（小 CNN / ViT-S）；接口 = 纯内部逻辑。
- **落地步骤**：①自动生成滑移伪标签（物体相对位移 + 夹爪闭合 + EE 加速度残差）；②训练 `m_t` 回归 / 分类器并做可靠性图；③取保守下界 `\underline{m}_t = m_t − δ`；④定义触发规则（连续 k 帧低于阈值）；⑤在 Unlock / Plug In Ethernet / Open Pill Bottle / Zip Up 上做专项 A/B；⑥与上一版二值抓握确认做消融。
- **风险**：①**可观测性不足**——1 维夹爪下 δ 很大，保守下界可能永远不触发；缓解：同时保留「失败后重抓」的兜底，并把 SlipMargin 定位为「提前量」而非唯一触发器。②伪标签在未见物体上漂移；缓解：置信度门控 + episode 内自校准。③误触发导致不必要的松手；缓解：只在「高置信滑移」时触发，且恢复步有正期望检查（P9）。

### IP-11 · DynaGuard 动作块安全包络（P0）

- **动机**：chunked VLA 的一次输出是一个开环承诺；在动态环境（人手、干扰物、自碰撞、payload）里，承诺期间环境会变。上一版的 chunk 缝合只保证边界连续，不保证「未来 T 步不碰」。DynaGuard 在动作块级别做保守安全认证，输出可执行前缀长度。
- **与现有方案的差异**：现有方案要么逐帧碰撞检查（太短视，无法处理 chunk），要么完全不做安全过滤。DynaGuard 是**运行时安全过滤器**：它不改变策略的任务意图，只截短 / 暂停 / 退让，因此合规且可审计。
- **技术可行性**：中。①用 4 路相机 + 本体感觉构造占据 / 障碍集；②用保守几何包络（球 / 胶囊 / 凸包）近似机器人 + payload；③用常速度 / 常加速度界做短时预测；④在 5–15 ms 内完成一次交检查。难点是感知噪声与保守性校准。
- **所需资源**：数据 = 官方数据 + 合成干扰；算力 = 小（几何 + 轻量感知）；接口 = 需要确认「能否返回短于声明上限的 chunk」。
- **落地步骤**：①复刻官方 client 语义（Q6）：chunk 如何执行、是否插值、是否接受变长；②实现保守扫掠集 `O^+` 与障碍集 `F^+`；③实现 `T_c = max{T : O^+_{1:T} ∩ F^+ = ∅}`；④实现事件触发中断（环境变化 / 跟踪误差超界）；⑤在合成人为干扰与自碰撞场景做压力测试；⑥真机 A/B：碰撞率、超时率、成功率。
- **风险**：①**保守性导致冻结**（本轮最大风险）；缓解：先只做「事件触发中断」、后做「预认证截短」，用 A/B 决定。②感知漏检 → 安全包络不 sound；缓解：用本体感觉 + 固定安全边距兜底，宁可保守。③接口不支持变长 chunk → 只能用「安全延拓」填充；缓解：先做 Q6 实测，不通过则退化到固定 chunk。

### IP-12 · CommitHorizon 承诺时域调度（P0）

- **动机**：固定 8/16 步 chunk 与状态探针中的方向反转间隔（中位 5–6 帧）同量级，长 chunk 会跨过多次需要反应的事件。承诺时域应该像步幅一样随「地形」变化：开阔搬运可以长，窄缝插入必须短。
- **与现有方案的差异**：现有方案把 `action_chunk_size` 当静态超参；我们把 `T_c` 定义为相位、拥挤度、安全认证的函数，并在每次调用时取 `min`。
- **技术可行性**：高（前提是接口允许变长返回；见 Q6）。`T_c` 的计算本身是 O(1)。
- **所需资源**：接口 = 官方 client；算力 = 极小；数据 = 无。
- **落地步骤**：①定义 `T_c = min(T_a^max, T_c^safe, T_c^phase)`（U20）；②相位上限：reach / grasp / align / insert 用 1–4，transport / place 用 8–16；③拥挤度用障碍集密度 / 最近距离调制；④最小驻留时间防止抖动；⑤A/B：固定 8 vs 自适应；⑥记录调用次数与 p99 延迟。
- **风险**：①短 chunk 增加调用次数 → 延迟 / 并发压力；缓解：只在必要相位缩短，并做 N 端口压测。②`T_c` 抖动 → 动作不连续；缓解：最小驻留 + 变化率限幅。③评测端把 `action_chunk_size` 当固定契约 → 变长返回被拒；缓解：保留固定长度安全网。

### IP-13 · RecoveryGait 恢复步库（P0）

- **动机**：上一版有「重抓 / 改抓 / 非抓取原语」，但触发条件是固定的「没抓住且重试 <3」，没有比较「继续」与「恢复」的期望收益。步态规划的恢复步之所以有效，是因为它只在「继续会摔」时补一步；桌面操作同理：不是失败就重试，而是**恢复的期望成功率 > 继续执行的期望成功率**时才恢复。
- **与现有方案的差异**：把恢复从「固定规则」升级为「带净收益判据的策略」；并给出最大重试次数与超时预算的联合约束。
- **技术可行性**：中。恢复原语可用数据检索 + 少量真机试错固化；期望收益可用轻量分类器估。
- **所需资源**：数据 = 官方数据 + 少量真机；算力 = 小；接口 = 纯内部逻辑。
- **落地步骤**：①定义恢复原语库 R（U21）：regrasp / retreat / reapproach / switch_arm / rotate_wrist / push / sweep / tilt；②为每个失败模式定义候选原语；③训练「恢复 vs 继续」的期望收益估计器；④加入最大重试 `N_r` 与总超时预算；⑤在 Unlock / Plug In Ethernet / Open Pill Bottle / Pick Out Battery 上 A/B；⑥记录「恢复救回 / 恢复恶化 / 继续成功 / 继续失败」四格。
- **风险**：①恢复动作破坏场景（推倒其他物体）；缓解：单物体场景优先 + 禁区。②期望收益估计不准 → 越救越糟；缓解：保守阈值 + 最多 2–3 次 + 可回滚到「继续」。③恢复引入抖动 → 被可信度审核注意；缓解：恢复决策稀疏、记录理由、保持时序规律。

### IP-14 · InterferenceBench 安全 / 干扰代理评测（P0）

- **动机**：上一版六因子分解没有「避障」和「恢复」两个因子；而本轮的两个新灵感恰好落在这两个因子上。没有代理评测，就无法在真机时段之外迭代 DynaGuard / RecoveryGait。
- **与现有方案的差异**：把「人为干扰」从一句泛化轴变成可控制、可重复、可分级的压力测试；并把安全指标（最小距离、碰撞次数、中止次数）纳入代理评测。
- **技术可行性**：中。①合成干扰：在官方数据回放 / 仿真里注入移动障碍、遮挡、突然出现的人手；②自碰撞：用本体状态做扫掠体检查；③安全指标可离线计算；④真机锚点用少量时段标定。
- **所需资源**：数据 = 官方 32 数据集 + 合成变体；算力 = 中；接口 = 无。
- **落地步骤**：①定义 5 级干扰强度（无 / 静态遮挡 / 慢速移动 / 快速移动 / 主动阻挡）；②实现可重复的注入脚本；③定义 `avoid` / `recover` 因子与安全指标；④离线跑 8 模型 × 32 任务的结构基线；⑤真机锚点标定（每轮 2–3 个时段）；⑥若相关性 <0.5，则只作压力测试，不作选型依据。
- **风险**：①合成到真机的 gap；缓解：真机锚点 + 只用于相对排序。②干扰注入过于人为 → 策略学到「假干扰」；缓解：多种注入方式 + 随机化。③安全指标与成功率冲突；缓解：分开报告，不混成一个分数。

### IP-15 · StanceProbe 基座 / pivot 零成本探针（P2）

- **动机**：上一版 IP-05 想用 WBT 数据做全身姿态先验；但本轮状态探针显示下肢方差仅为手臂的 1/5573，说明官方操作数据里几乎没有基座运动。继续投入腿式 / 全身步态很可能是 OOD。
- **与现有方案的差异**：不直接做姿态先验，而是先做一次零成本探测：pivot 是否被评测端跟踪？改变 pivot 是否改变可达性？如果答案是否，立即砍掉。
- **所需资源**：接口 = 官方 client；算力 = 极小；数据 = 无。
- **落地步骤**：①发一组小 pivot 偏移，观察 EE / 本体是否响应；②在边界目标任务上测可达率；③若跟踪误差大或收益为 0，停止投入；④仅在探针为正时，才考虑把 IP-05 重新纳入。
- **风险**：pivot 语义未知 / 被忽略 ⇒ 收益为 0；因此设为 P2，且**不进入 MVP**。

**定义 U13（接触模式）** 在时刻 `t`，系统处于 `s_t ∈ S`；`s_t` 由 CSHA 的离散状态给出，而不是由独立分类器直接输出。

**定义 U14（CSHA）** `H = (S, E, G, I, R, Flow)`，其中 `E ⊆ S×S` 为允许的切换边，`G = {G_e}_{e∈E}` 为 guard，`I = {I_s}_{s∈S}` 为 invariant，`R = {R_e}_{e∈E}` 为 reset，`Flow_s` 为模式 `s` 内的连续动作流（由策略主干给出）。

**定义 U15（guard 与 invariant）** `G_{s→s'}(o_t, x_t) ∈ {0,1}` 是切换使能；`I_s(o_t, x_t) ∈ {0,1}` 是模式内必须持续满足的条件。切换规则：仅当 `G_{s→s'}=1` 且 `s'` 的初始 invariant 在 reset 后成立时才切换；若 `I_s=0` 且没有可用 guard，则进入 `safe_stop` 或 `recover`。guard 至少包含：抓握确认、滑移、对齐误差、插入误差、碰撞风险、超时。

**定义 U16（接触稳定裕度）** `m_t = σ(f_θ(g_t, Δgrip_t, a_ee,t, v_ee,t, w_t))`，其中 `g_t` 为夹爪开合，`Δgrip_t` 为闭合速率，`a_ee,t` / `v_ee,t` 为末端加速度 / 速度，`w_t` 为腕部视觉特征；`\underline{m}_t = m_t − δ`，`δ` 为未观测分量的保守界。

**定义 U17（滑移事件）** `E_slip(t) = 1` 当且仅当 `\underline{m}_{t-k+1:t} < τ_m` 连续 `k` 帧；触发后 CSHA 从当前模式切到 `recover`（优先 `regrasp` 或 `retreat`）。

**定义 U18（安全包络）** `O^+_{t:t+T}(a_{1:T})` 是机器人（含 payload）在 `a_{1:T}` 下未来 `T` 步占据集的保守过近似；`O^+` 必须包含真实占据集（soundness）。

**定义 U19（障碍集）** `F^+_{t:t+T} = F^+_self ∪ F^+_env ∪ F^+_human ∪ F^+_payload`，分别为自碰撞、桌面 / 容器、人手 / 人体、payload 与环境的禁区；每项都是保守过近似。

**定义 U20（承诺时域）** `T_c = min(T_a^max, T_c^safe, T_c^phase)`，其中 `T_c^safe = max{T ≤ T_a^max : O^+_{1:T} ∩ F^+_{1:T} = ∅}`（无解时取 0，进入 `safe_stop` / `retreat`）；`T_c^phase` 由 U8 的相位上限给出。

**定义 U21（恢复原语库）** `R = {regrasp, retreat, reapproach, switch_arm, rotate_wrist, push, sweep, tilt}`；每个原语有前置条件、动作模板、最大时长与禁区约束。

**定义 U22（恢复策略）** `π_rec(f_t) = argmax_{r∈R(f_t)} \hat{P}(success | r, f_t)`，其中 `f_t` 为失败模式（未抓住 / 滑移 / 对齐失败 / 插入卡死 / 碰撞风险 / 超时）；仅当 `\hat{P}(success|r) > \hat{P}(success|continue)` 且 `n_retry < N_r` 时执行。

**定义 U23（相序）** `σ = (s_0, …, s_K)` 是 CSHA 的一次运行轨迹；相邻模式满足 `(s_i, s_{i+1}) ∈ E` 且切换时 guard / invariant 成立。

**定义 U24（安全证书）** 每次 `get_action` 产生 `C = (t, s_t, T_c, O^+, F^+, decision, latency, jerk)`，其中 `decision ∈ {full, truncated, paused, retreat, recover}`；证书可导出、可回放，用于自证可信度。

```python
                "observation.state.right_arm": [-4, -2, 0],
                "observation.state.left_ee_pose_gripper_base":  [-2, 0],
                "observation.state.right_ee_pose_gripper_base": [-2, 0],
                "observation.state.left_gripper":  [-2, 0],
                "observation.state.right_gripper": [-2, 0],
                "observation.state.lower_body": [-2, 0],
            },
            "image_resize": {
                "observation.images.cam_left_high":  [240, 320],
                "observation.images.cam_right_high": [240, 320],
                "observation.images.cam_left_wrist":  [240, 320],
                "observation.images.cam_right_wrist": [240, 320],
            },
            "action_chunk_size": 16,                  # 上限；运行时由 T_c 截短
            "token": os.environ["UNIBOT_SUBMISSION_TOKEN"],
        }

    def reset(self, port=None):
        self.sessions.setdefault(port, Session()).reset()

    def get_action(self, obs, port=None):
        s = self.sessions[port]
        t0 = time.perf_counter()

        # 1) 感知：障碍 / 自碰撞 / payload
        F = self.guard.obstacles(obs)                  # U19: 保守过近似
        # 2) 稳定裕度与滑移 guard
        m = self.slip.lower_bound(obs)                 # U16
        slip = self.slip.event(m, s.hist)              # U17
        # 3) CSHA 模式推进（事件触发，带最小驻留）
        s.mode = self.csha.step(s.mode, obs, m, slip, s.dwell)  # U14/U15

                s.n_retry += 1
                a = self.rec.rollout(r, obs, s)
                return self.pack(a, s, t0, decision="recover")

        a = self.model.act(obs, s.task_token, s.mode, s.context, self.metadata["action_chunk_size"])

        Tc_safe = self.guard.certify(a, obs, F)        # U18/U20
        Tc = self.ch.combine(Tc_safe, s.mode, F)       # U20
        if Tc == 0:
            a = self.rec.safe_stop_or_retreat(obs, s)  # 不硬闯
            return self.pack(a, s, t0, decision="retreat")
        a = a[:Tc]
        # 7) 记录安全证书（延迟 / jerk / 决策）
        self.audit.log(t0, s.mode, Tc, F, "truncated" if Tc < len(a) else "full")
        s.last_action = a[-1]
        return self.pack(a, s, t0, decision="full" if Tc == self.metadata["action_chunk_size"] else "truncated")

    def pack(self, a, s, t0, decision):
        out = {
            "meta.token": os.environ["UNIBOT_SUBMISSION_TOKEN"],
            "action.left_gripper":  a["left_gripper"][:, None].astype(np.float32),
            "action.right_gripper": a["right_gripper"][:, None].astype(np.float32),
            "action.left_arm":  a["left_arm"].astype(np.float32),
            "action.right_arm": a["right_arm"].astype(np.float32),
        }
        self.audit.mark(out, s.mode, decision)
        return out
```

```python
# ===== IP-09：接触相序混合自动机 =====
class CSHA:
    MODES = ["reach", "grasp", "lift", "transport", "align",
             "insert", "place", "release", "recover", "safe_stop"]

    def step(self, s, obs, m, slip, dwell):
        # invariant 检查：违反则优先进入 recover / safe_stop
        if not self.invariant(s, obs, m):
            return "recover" if s not in ("recover", "safe_stop") else "safe_stop"
        if dwell < MIN_DWELL:
            return s
        # 事件触发 guard（按优先级）
        if slip:
            return "recover"
        if s == "reach" and grasp_confirmed(obs):
            return "grasp"
        if s == "grasp" and lift_confirmed(obs):
            return "lift"
        if s == "lift" and transport_ready(obs):
            return "transport"
        if s == "transport" and near_target(obs):
            return "align"
        if s == "align" and aligned(obs):
            return "insert"
        if s == "insert" and inserted(obs):
            return "place"
        if s == "place" and released(obs):
            return "release"
        return s

    def invariant(self, s, obs, m):
        if s in ("grasp", "lift", "transport", "align", "insert", "place"):
            return m >= M_MIN              # 接触期间必须保持稳定裕度
        return True
```

```python
# ===== IP-10：滑移裕度 =====
class SlipMargin:
    def lower_bound(self, obs):
        w = wrist_feat(obs)                        # 腕部视觉
        dg = gripper_rate(obs)                     # 闭合速率
        a = ee_accel(obs)                          # 末端加速度
        v = ee_vel(obs)                            # 末端速度
        m = torch.sigmoid(self.net(torch.cat([w, dg, a, v]))).item()
        return m - self.delta                      # 保守下界（U16）

    def event(self, m, hist):
        hist.append(m)
        k = self.k
        return len(hist) >= k and all(x < self.tau_m for x in hist[-k:])
```

```python
# ===== IP-11：动作块安全包络 =====
class DynaGuard:
    def obstacles(self, obs):
        # 保守过近似：自碰撞 / 桌面 / 人手 / payload
        return {
            "self": self_swept_capsules(obs),
            "env":  table_and_receptacles(obs),
            "human": human_tubes(obs, horizon=self.H),
            "payload": payload_hull(obs),
        }

    def certify(self, a, obs, F):
        O = self.swept_volume(obs, a)              # 含 payload 的保守扫掠集
        for T in range(1, len(a) + 1):
            if intersects(O[:T], F, margin=self.safety_margin):
                return T - 1                        # U20: 安全前缀
        return len(a)
```

```python
# ===== IP-12 + IP-13：承诺时域与恢复步 =====
class CommitHorizon:
    def combine(self, Tc_safe, mode, F):
        phase_cap = {"reach": 4, "grasp": 2, "align": 3, "insert": 2,
                     "transport": 16, "place": 8, "release": 2}.get(mode, 8)
        crowd = clamp(1.0 - self.clutter(F), 0.3, 1.0)
        return max(1, min(Tc_safe, phase_cap, int(phase_cap * crowd)))

class RecoveryGait:
    def select(self, obs, failure, n_retry):
        if n_retry >= self.N_r:
            return None
        cands = self.candidates[failure]
        # U22: 只在恢复期望 > 继续期望时恢复
        best = max(cands, key=lambda r: self.p_success(r, obs))
        return best if self.p_success(best, obs) > self.p_continue(obs) else None
```

```python
# ===== IP-14：七因子分解（上一版六因子 + avoid / recover）=====
def failure_taxonomy(episode, phase_labels, safety_events):
    factors = ["reach", "grasp", "transport", "align", "insert", "release",
               "avoid", "recover"]
    out = {f: 1.0 for f in factors}
    # 首个失败点之后的因子被吸收；avoid/recover 由安全事件单独估计
    out["avoid"] = 1.0 - safety_events["collision_rate"]
    out["recover"] = safety_events["recovered"] / max(1, safety_events["failures"])
    return out
```

## 5. 推导（引理 L8–L14）

**引理 L8（CSHA 的保守扩展）** 若基线策略作为每个非恢复模式的 `Flow_s` 被嵌入 CSHA，且 guard 只切换到 `recover` / `safe_stop`，则：在没有任何 guard 触发的 episode 上，CSHA 与基线逐动作等价；在 guard 触发的 episode 上，成功率变化满足
`Δ ≈ P(trigger)·(Δ_recover − Δ_continue) − P(false_trigger)·L_false − overhead`。
因此 CSHA 不劣于基线的充分条件是 `P(trigger)·Δ_recover ≥ P(false_trigger)·L_false + overhead`。这给出一个可实测的准入判据：guard 的假触发率必须低于恢复增益与误伤损失的比值。∎

**引理 L9（安全包络的充分性）** 若 `O^+` 是真实占据集的 sound over-approximation，`F^+` 是真实禁止集的 sound over-approximation，则 `O^+ ∩ F^+ = ∅ ⇒` 真实占据集与真实禁止集不相交；因此 `T_c` 是真实安全时域的下界。保守性只降低可执行前缀长度，不破坏安全性。∎

**引理 L10（承诺时域的单调性）** 在障碍速度上界 `v_max` 与跟踪误差上界 `ε` 下，chunk 内碰撞概率随 `T` 单调不降；而调用次数（∝`1/T`）导致的延迟 / 降级成本随 `T` 单调不增。故存在相位相关的 `T*` 使加权和最小；固定 `T` 一般不是最优，除非碰撞成本与延迟成本恰好抵消。∎

**引理 L11（稳定裕度的保守下界）** 若 `m_t` 是摩擦锥裕度的单调函数，未观测分量有界 `|δ_t| ≤ δ`，则 `\underline{m}_t = m_t − δ` 是真实裕度的下界；触发规则 `\underline{m}_t < τ_m` 的漏报率由 `δ` 与真实分布决定，且随 `δ` 增大而增大。1 维夹爪下 `δ` 较大，故该规则**偏保守、易漏报**，必须保留「失败后重抓」的兜底。∎

**引理 L12（恢复步的净收益）** 若仅在 `\hat{P}(success|recover) > \hat{P}(success|continue)` 时恢复，且每次恢复的期望代价有界，则恢复策略的期望成功率不低于「从不恢复」；最大重试 `N_r` 给出最坏情况时间上界 `N_r·τ_rec`。证明：把每次决策看成在「继续」与「恢复」之间取估计收益较大者，按可选停时（optional stopping）归纳。∎

**引理 L13（相序可辨识性）** 若各模式的 guard 信号（夹爪闭合、EE 速度、腕部几何、对齐误差）在数据中可分离，则相序 `σ` 在标签置换意义下可辨识；所需样本量随模式数 `|S|` 与 guard 噪声线性增长。若某两个模式的 guard 信号不可分离（例如 grasp 与 lift 在单自由度夹爪下几乎同分布），则必须合并模式，否则 guard 误触发率不可控。∎

**引理 L14（干扰基准的可迁移性）** 合成干扰可估计安全包络的 ROC，但其与真机的相关性受 sim-to-real gap 限制；若真机锚点的 Spearman `|r| < 0.5`，则合成基准只能作为压力测试，不能作为选型依据。该判据与上一版 E601 的剪枝预案同构。∎

| **人为干扰 OOD**（训练数据几乎没有） | 高 | 中 | 合成干扰只作压力测试；真机锚点标定；不把合成分数当选型依据 |
| **可信度审核把中断当异常交互** | 中 | 中 | 安全证书 + 稀疏恢复 + 保持时序规律；主动导出报告 |
| **下肢 / 腿式步态 OOD** | 高 | 中 | 探针已显示下肢方差 1/5573；直接砍掉腿式步态，只保留接触相序 |
| **guard 误触发导致抖动** | 中 | 中 | 最小驻留 + 连续 k 帧确认 + 置信度门控 |
| **恢复动作破坏场景** | 中 | 中 | 单物体优先 + 禁区 + 最多 2–3 次 |
| **过拟合 teaser** | 中 | 中 | teaser 仅作结构参考；一切选型以本地 OOD + 真机 A/B 为准 |

**剪枝预案（下一轮起执行）**：

- **必保**：IP-09（相序形式化）、IP-11（安全包络）、IP-14（代理评测）——信息价值 + 机制正确性。
- **优先深化**：IP-12（承诺时域）与 IP-10（滑移裕度）——直接对应本轮探针的两个信号。
- **条件推进**：IP-13（恢复步）依赖 E624；若恢复期望估计不可靠，只保留 regrasp/retreat。
- **直接砍掉**：IP-15 若探针不通过；腿式步态永远不进主线。

## 11. 本轮最值得押注的创新点（一句话）

**押注 IP-09 + IP-11 的组合：把桌面操作从「一条开环 chunk」改写成「接触相序上的准静态步态 + 动作块级安全包络」——它同时命中了本轮两个灵感的真正难点（步态的事件触发换相、避障的时域承诺），又用零成本探针避开了「腿式步态 OOD」这个最容易走偏的坑；即使 DynaGuard 最终因保守性被砍，CSHA 与 SlipMargin 仍能独立成立，属于下行有底、上行有想象力的下注。**

**本轮最大风险（一句话）**：安全包络的保守性会在窄缝 / 近接触相位制造「冻结—抖动—超时」的新失败模式，把本来能靠一次果断插入成功的回合变成永远不敢插入的回合。
