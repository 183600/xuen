# 第 51 轮（承接第 50 轮 v14；灵感循环第 6 轮；本轮灵感：决策规划 × 关节驱动） · CoStride-PIVOT：计划骨架证书 × 执行能力包络 × 驱动感知重规划（v15）

> 承接第 50 轮 v14 CoStride-Distill。v14 用"提议-处置"把搜索逐出安全路径，用混合可行性证书与捕获域把双足安全从"可停"改成"可捕获"，用能力格把用户共创收进双签署契约。但它仍隐含两个未被点破的承重假设：**H11：计划与证书是解耦的——HTD-Cert 产出一条"待逐段认证"的计划，认证只发生在"下一个动作"上；谁来决定"何时放弃这条计划"、决策分支点是否有预置退路、重规划延迟期间机器人靠什么保持安全，都未被认证**。**H12：执行器是可信且恒定的——证书里的控制界 `U_b` 被当作静态、真实可达的硬上界，且命令力矩会被关节如实交付；忽略了力矩-转速-温度-电压耦合的降额、带宽/延迟/回差、老化与故障，也忽略了"抽象力矩被认证 ≠ 真实关节已交付"**。两个灵感词精确命中：**决策规划**要求安全从"动作级"升级为**策略级**——证书必须覆盖"计划骨架 + 每个决策/环境分支的认证出口 + 来得及重规划"；**关节驱动**要求安全从"状态空间"下沉到**执行能力空间**——证书必须条件于运行时认证的驱动包络 `A_lb(t)`，并由交付证明保证抽象力矩真的变成关节力矩。二者耦合出一个反直觉、且会致命的悖论：**双足最需要捕获步的时刻（长走之后被人推撞），恰是关节最热、包络最窄、捕获力矩最不够的时刻**——v14 的捕获域 `C_k` 是在"电机冷且健康"下认证的，长程任务会把它悄悄掏空。于是本轮把 `C_k` 变成随时间/热预算收缩的 `C_k(t;b_a)`，把"计划是否可行"变成"资源约束下的可行性"，把"重规划"变成受实时可调度性约束的认证动作。

## 0. 直觉与动机

**灵感 1（决策规划 → 从"动作级过滤"到"策略级认证"）**
直觉：v14 的守卫像一个极其负责的副驾：每次只批准"下一个动作"，却从不检查"这条路前面有没有掉头口"。真实决策规划里，危险往往不在下一步，而在**分支点**：选"绕远但稳"还是"抄近但窄"、在走廊尽头继续直行还是等待、交接时先松手还是先挪步。环境（尤其人）是**对手**而非噪声，所以正确对象是**博弈的策略**，不是单条轨迹：要存在一个机器人策略，使得**任意环境走法**下都还有一条认证退路。进一步，重规划不是免费的：规划+守卫+仲裁要花 `τ_rp` 毫秒，在这段时间里机器人还在执行旧计划。如果旧计划在 `τ_rp` 内就可能撞线，那么"我打算重规划"这个决定本身就是不安全的。安全因此多了一条**及时性**：要么在 `t_boundary−τ_rp` 之前就已触发重规划，要么根本不该提交当前动作。这把决策规划问题第一次变成**实时可调度性**问题。

**灵感 2（关节驱动 → 证书必须条件于"此刻真的能出多大力"）**
直觉：v14 的 `U_b` 是一个写在纸上的常数，可真实关节的可用力矩是**会呼吸的**：转速越高力矩越低（反电动势），温度越高允许电流越低（铜损/绝缘），母线电压跌落直接压低最大力矩，回差和摩擦吃掉小力矩精度，老化和故障让某些关节随时"罢工"。更微妙的是**认证发生在抽象力矩空间，交付发生在关节空间**：守卫批准了 `τ_cmd`，但驱动器可能因过流限幅、延迟、抱闸或编码器故障而没有交付 `τ_real≈τ_cmd`。"证书说可行"和"机器人真的做到了"之间有一条**虚拟-真实缺口**。因此正确的对象不是静态 `U_b`，而是运行时**认证的能力下界** `A_lb(t)`：它是真实能力 `A_true(t)` 的内近似（可证明不会高估），由可测温度/电压上界与经形式化验证的保守降额模型构造；守卫只用 `A_lb`，规划器/学生可以用更乐观的估计 `A_est`。这与 v14"近似搜索、绝不近似评估"是**同一条不对称**：估计-保证之差 `ΔA` 只损失可用性，不损失 soundness。

**灵感 3（耦合 → 热-捕获悖论与驱动预算）**
直觉：连续行走会持续给踝/膝关节加热，`A_lb` 收缩 → 捕获步所需峰值力矩先不够 → `C_1,C_2` 收缩 → 一旦被推就更容易进入保护姿态。也就是说，**任务越接近尾声、越累，安全边际越小**，而人机共处的推撞风险并不会因为机器人累了而降低。正确的做法不是"走慢点"这种粗糙折中，而是把**驱动预算**（热负载/能量）作为计划的一等资源：每条计划边消耗预算，预算抬高温度、收缩包络；计划可行性在 `A_lb(t;b_a)` 下评估；必要时规划器插入"散热停留"或改走短程分段。这把"决策规划 × 关节驱动"耦合成了一个可计算的**资源约束可行性**问题，而不是一句安全口号。

**灵感 4（决策规划 × 提议-处置 → 乐观学生与保守守卫的重规划分工）**
直觉：学生可以在 `A_est` 下快速提议"走这条分支、这里该重规划"，但守卫必须在 `A_lb` 下复核"这条分支的出口在承诺视界内仍成立、触发来得及"。学生提议错了只导致回退/提前保守，不导致放行未认证动作。重规划本身也遵循提议-处置：学生提议重规划时机与目标，守卫检查及时条件与出口存在性——重规划不是逃生门，而是一个需要被认证的动作。

**灵感 5（关节驱动 × 原型证伪 → 热瞬态与故障注入的证伪阶梯）**
直觉：降额模型最容易在**瞬态**上翻车：刚加速时的电压跌落、长时间行走后的热饱和、堵转瞬间的过流。PFV 原型阶梯必须加入热瞬态、电压跌落、堵转、编码器跳变、抱闸异常与老化；但只有精确证伪器能定罪 `A_lb` 越界。JDA 的交付失败样本回灌 DCL，既教学生避开"热上更易失败"的动作，也让 EDR 的热预测更准——证伪的是包络模型，而不是"感觉更稳"。

**耦合升级**：v14 八层之上新增 **L0 驱动能力层（ACC/JDA）** 与贯穿 L2–L4 的**决策可调度性纵向通道（PSC/CRT/EDR）**；联合状态扩为 `z=(x_r,x_h,x_e,κ,a_drive)`（`a_drive`=关节驱动状态）；JCPS 联合输出追加 `π_branch`（计划分支/出口选择）与 `ρ_a`（包络裕量）。v15 仍不推倒 v14；它是给 v14 的两条"纸面承重梁"（计划可放弃性、执行器可信性）装上真实的证书。

## 1. 形式化定义（增量：定义 87–94）

**定义 87（关节驱动能力状态与能力包络）**
单关节驱动状态 `a_j=(τ_j,ω_j,θ_j,T_j,V_bus,f_j)`（力矩/角速度/角度/温度/母线电压/故障位）。能力包络 `A(t)=∏_j A_j(t)`，`A_j(t)={τ_j: |τ_j|≤τ_max^j(ω_j,T_j,V_bus) ∧ f_j=0}`；`τ_max^j` 由经标定的降额模型 `M_derate`（力矩-转速曲线 × 温度降额 × 电压降额）给出。真实能力 `A_true(t)` 不可直接观测；运行时构造 **认证下界** `A_lb(t)⊆A_true(t)`（由可测温度/电压的保守上界 + 经形式化验证的最坏瞬态降额推出）与**乐观估计** `A_est(t)⊇A_lb(t)`（供学生/规划器）。v14 的静态 `U_b` 被 `A_lb(t)` 取代；`A_lb` 构造器带版本哈希 `h(A)`。红线：`A_lb` 禁止用统计均值/未验证外推，必须覆盖热瞬态与电压跌落的最坏情形。

**定义 88（驱动条件化可行证书）**
用 `A_lb(t)` 替换 `Σ_b` 的控制界，得 `V_A(T)={z_0: ∃有界轨迹, ∀t≤T z(t)∈Z_safe, z(T)∈M_stand, u(t)∈A_lb(t)}`、`B_v^A(z,q;A_lb)`，且 `B_v^A≥0 ⇒ z∈C_cert^A ⊆ V_A(T)`（内近似不变）。证书附带**包络裕量** `ρ_a(z,q)≥0`：能力包络在此收缩半径内证书仍成立，即 `A_lb(t')⊇A_lb(t)⊖ρ_a ⇒ B_v^A` 继续有效。`ρ_a` 是可计算、可入账的部署量，把"证书对驱动漂移的鲁棒性"显式化，而非藏在静态界里。

**定义 89（计划骨架与认证出口）**
计划升级为决策-环境交替的 AND-OR 博弈 `G=(N,n_0,N_goal,E_rob,E_env,Exit,H_dec)`：`E_rob` 为机器人决策边（子任务/分支/步态），`E_env` 为环境或人的走法（chance/adversarial），`Exit:N→{V_A,C_k,Protective}` 为每个可达节点预置的认证出口。`G` 认证当且仅当存在机器人策略 `π`，使**任意环境走法**下沿 `π` 在 `H_dec` 内到达 `N_goal`，或到达某出口节点 `n` 且 `Exit(n)` 在**承诺视界 `H_commit` 内对 `A_lb` 最坏包络**仍认证。这把"逐动作认证"升级为"策略级认证"：放行的不是下一步，而是"下一步之后处处有认证退路"。

**定义 90（承诺视界与可调度重规划触发）**
`τ_rp` 为重规划实测上界（规划+精确守卫+通信+仲裁），`τ_stale=τ_rp`。在 `z` 提交沿 `π` 的下一动作前必须满足**及时条件**：`time_to_boundary(z)>τ_rp+τ_ttb_min`，且提交后的预测轨道在 `[t,t+τ_rp]` 内 `B_v^A≥0`。重规划触发谓词 `R(z,A)` 为真当且仅当任一：(i) 证书裕量低于缓冲；(ii) 预测包络漂移 `(dA/dt)·τ_rp` 吃掉裕量；(iii) 当前分支在环境走法下的出口距离超过阈值；(iv) 交付证明衰减。`R` 必须在 `t_boundary−τ_rp` 之前触发。计划不仅要可达，还要**来得及改**——这是把决策规划纳入实时可调度性。

**定义 91（驱动预算与资源约束可行性）**
计划边带执行代价 `c_e`（能量/热负载/时间），累积为驱动预算 `b_a(t)`；热负载抬升温度 → 收缩 `A_lb(t;b_a)` → 收缩捕获域 `C_k(t;b_a)`。可行性因此是**资源约束可行性**：`V_A(T;b_a)`；`G` 认证要求最坏环境走法下预算不耗尽。核心推论：长走使 `|C_k|` 单调收缩，故"长走—交接/避碰"计划必须显式预留**捕获力矩预算**；规划器可插入"散热停留"作为合法决策边，而这一边同时消耗时间预算。

**定义 92（关节交付证明与虚拟-真实缺口）**
命令 `τ_cmd` 与实测 `τ_real` 在健康时满足 `|τ_real−τ_cmd|≤δ_τ`、延迟 `≤l_max`、跟踪误差 `≤e_max`，并由每关节看门狗与编码器/电流交叉校验**证明**（JDA）。认证只覆盖"已证明交付"的力矩；交付证明失效（过流、堵转、编码器跳变、抱闸异常）即 fail-closed 到认证保护姿态。证书在抽象力矩空间成立、真实关节可能未交付，这条**虚拟-真实缺口**记为 `α_del`。

**定义 93（包络的估计-保证二分与版本钉住）**
学生/规划器用 `A_est`（快、乐观、可学习），守卫只用 `A_lb`（保守、可证明），`A_lb⊆A_est`。二者之差 `ΔA=A_est\A_lb` 只影响**可用性**（学生会提议守卫会拒的乐观动作），不影响 soundness——与 v14"近似搜索、绝不近似评估"同构。`M_derate` 与 `A_lb` 构造器带版本哈希 `h(A)`，与契约版本 `h(κ_c)` 一起钉入守卫；模型更新触发再认证，旧包络版本候选一律拒（fail-closed）。

**定义 94（十源归因与账本）**
`CCL++` 追加：计划骨架认证/分支选择/重规划触发、包络漂移、交付证明失败、驱动预算消耗；DDA 扩为**十源**：感知 / 关节证书 / **驱动（包络·交付）** / 边界 / 意图 / 接触 / 传输 / 动力（可行·捕获）/ 蒸馏 / **决策（计划·重规划）**。任一源折损显式入账并参与抽象/速度/捕获域缩放，不得静默吸收。

## 2. 新增产出与既有 IP 升级

**IP-91 PSC（Plan Skeleton Certificate）**：计划骨架 AND-OR 博弈 + 每分支预置认证出口；策略级（而非动作级）放行。
**IP-92 CRT（Certified Replan Trigger）**：承诺视界 + 及时条件 + 可调度重规划触发；把"何时放弃计划"变成被认证的决策。
**IP-93 ACC（Actuation Capability Certificate）**：运行时力矩-转速-温度-电压包络；`A_lb` 内近似 + `ρ_a` 裕量 + 降额模型版本钉住。
**IP-94 JDA（Joint Delivery Attestation）**：每关节交付证明（残差/延迟/跟踪/故障交叉校验）；虚拟-真实缺口 `α_del` 入账。
**IP-95 EDR（Envelope-Drift Replanner）**：包络漂移预测驱动重规划与再认证；把热-捕获悖论变成可触发的安全事件。

**既有 IP 升级**
IP-73 JCPS：联合调度输入加计划骨架与 `A_lb`，输出加 `π_branch` 与 `ρ_a`；提交前过及时条件。
IP-87 HVC：`B_v` 升级为 `B_v^A`，条件于 `A_lb`；新增包络裕量 `ρ_a` 与包络漂移复核。
IP-88 CRM：捕获域按 `A_lb(t;b_a)` 评估，长走任务预留捕获力矩预算；`C_k` 随时间单调收缩。
IP-89 KDX：候选含计划分支；学生在 `A_est` 提议、守卫在 `A_lb` 精确处置；分歧仍只降可用性。
IP-90 LFF：场景分布加入热瞬态/电压跌落/堵转/编码器跳变/老化；只给预算优先级，无定罪权。
IP-86 UCC：共创条款（如"走快一档"）先经 `A_lb` 与捕获域剪辑；热预算不足即解释并降级，不静默折中。
IP-83 PFV：原型阶梯新增热瞬态、电压跌落、堵转、回差、老化注入；证伪对象含 `A_lb`/`M_derate`。
IP-84 XFER：传输缺口 δ 增"驱动保真"维度（仿真/缩比/真机的力矩-热对标）。
IP-77 DDA：八源 → 十源（+驱动、+决策）。
IP-61 DCL：采集包络漂移、交付残差、重规划漏触发、热近失四类样本。
IP-62 CCA：新增降额模型投毒、热瞬态规避、交付证明欺骗、重规划 DoS/抖动红队。
IP-51 CAR：守卫条件加"`A_lb` 通过 ∧ `h(A)` 匹配 ∧ JDA 交付证明正常 ∧ 及时条件成立"。
IP-45 总线：新增 actuation-envelope / delivery-attestation / plan-branch / replan-trigger 话题。
IP-75 ASC：抽象可行性在 `A_lb` 与驱动预算下评估；窄包络或低预算强制细化/分段。
IP-74 HTD-Cert：分解节点升级为计划骨架节点，每个决策/环境节点必须挂认证出口。
IP-72 RRP：e-process 纳入包络下界、交付证明、重规划及时性证据；跨层仍带 δ。
IP-76 CCL：CCL++ 追加决策/驱动事件（定义 94），仍只追加。

## 3. 算法骨架

每个宏周期：
1. 读目标、证书 `C_t`、租约、`CCL++`、契约版本 `h(κ_c)`、包络版本 `h(A)`；任一失效或审计失败 → fail-closed。
2. L0 采集关节驱动状态，构造 `A_lb(t)`（保守）与 `A_est(t)`（乐观），记录 `ρ_a` 与 `h(A)`；JDA 交叉校验交付健康。
3. HTD-Cert 展开为**计划骨架** `G`：前沿节点标注交互子任务 `ι`、步态子任务 `κ`、决策/环境分支与预置出口。
4. PSC 认证 `G`：反向吸引集求不动点；不可达 `N_goal` 的节点必须在 `H_commit` 内存在 `A_lb` 下仍成立的出口（`V_A`/`C_k`/保护姿态），否则拒该骨架并重分解。
5. 更新意图信念 `b'`（共创锐化）；计算 `σ(b')`；σ 低于阈值只保留 primitive/CRM。
6. UCC 校验共创条款：能力格 + 不可委托 + 双签署；通过后按 `A_lb` 与捕获域剪辑，再触发异步重解/重蒸馏；旧版本学生与旧包络候选即刻失效。
7. KDX 提议-处置：学生在 `A_est` 下提议 `(u_r,a,m,q,ι,κ,π_branch)`；`G_exact` 在 `A_lb` 下精确求值 `B/B_v^A/PFL/Inv/共识/版本/双哈希/租约`；通过才进入提交判定。
8. CRT 及时判定：若 `time_to_boundary ≤ τ_rp+τ_ttb_min` 或 `[t,t+τ_rp]` 内预测轨道越界 → 不提交，立即 `replan_now`；否则提交并预留 `ρ_a`。
9. EDR 监控包络漂移：`(dA/dt)·τ_rp` 吃掉裕量、或 `h(A)` 变化导致出口不再认证 → 触发驱动感知重规划（学生提议新分支/散热停留，守卫复核出口）。
10. 执行时 JDA 每关节交付证明；残差/延迟/故障越界即 fail-closed 到认证保护姿态；执行前后 CBG+ 复核边界∧屏障∧可行∧PFL∧共识∧双哈希。
11. 实测违反（含热-捕获失败/交付缺口）：DDA 十源归因，选最早安全点再分解/重校准/再蒸馏/再认证；必要时 CRM。
12. 离线/并行：PFV+LFF 按预算证伪（含热瞬态/电压跌落/故障注入），XFER 估计 δ，反例回灌 DCL/CCA 并共蒸馏 student/LFF/EDR；所有路径均不可行 → 技能合成/人工接管/保护姿态/fail-closed，绝不绕过 L0、L3.5 与精确守卫。

## 4. 本轮最大风险

**一句话**：整套 v15 的 soundness 现在悬挂在一个新的下界模型与两个新的时延量上——**降额包络下界 `A_lb⊆A_true` 必须在热瞬态/电压跌落/老化下仍不高估**、**关节交付证明 `JDA` 必须真的覆盖未检测故障**、**重规划上界 `τ_rp` 与触发提前量必须真的来得及**；任一下界被瞬态击穿、任一交付被静默失败、或重规划在 `t_boundary` 之后才发生，则"计划有认证出口、证书条件于真实能力"的论证就会退化为"纸面有退路、现实来不及"，因此包络下界必须最坏瞬态标定+形式化验证+持续证伪、交付必须每关节交叉校验+fail-closed、重规划必须实测上界+看门狗+提前缓冲，宁可保守失去可用性，绝不放松。

```
def certified_envelope(a_drive, derate_model, h_A):
    A_lb = Envelope()
    for j in JOINTS:
```

### IP-91 PSC（策略级认证）
```
def certify_plan_skeleton(G, A_lb_horizon, C_k):
    # AND-OR 反向吸引集：机器人选(E_rob)、环境选(E_env)
    attr = set(N_goal); changed = True
    while changed:
        changed = False
        for n in G.N:
            if n in attr: continue
            if any((n,m) in G.E_rob and m in attr for m in G.N):
                attr.add(n); changed = True
            elif all((n,m) in G.E_env and m in attr for m in G.N):
                attr.add(n); changed = True
    for n in reachable(G):                      # 可达但到不了目标
        if n not in attr:
            if not exit_certified(n, A_lb_horizon, C_k, H_COMMIT):
                return ('reject_skeleton', n)   # 无认证退路：拒
    return ('certified', attr)

def exit_certified(n, A_lb_horizon, C_k, H_commit):
    e = G.Exit[n]                               # V_A / C_k / Protective
    return e.holds_under(worst_case(A_lb_horizon, H_commit), C_k, H_commit)
```

```
def timely_commit(z, pi_next, A_lb, tau_rp, C_k):
    if time_to_boundary(z) <= tau_rp + TAU_TTB_MIN:
        return ('replan_now', 'lead_time_insufficient')

    if any(evaluate_BvA(zz, A_lb) < 0 for zz in z_pred):

    if plan_margin(z_pred[-1]) < RHO_BUFFER:

def replan_needed(z, A_lb, A_est, dA_dt, tau_rp):
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| ACC | 在线 O(n_j) 查表/求值 | O(n_j) | `A_lb⊆A_true` 内近似；`h(A)` 版本钉住 |
| PSC | 离线 O(|N|+|E|) 吸引集；在线 O(1) 出口查表 | O(|N|) | 任意环境走法有认证出口；否则拒骨架 |
| CRT | 在线 O(1) 谓词 + 视界预测 | O(1) | `time_to_boundary>τ_rp+τ_ttb`；陈旧窗口内可行 |
| JDA | 在线 O(n_j) 每周期 | O(1) | 残差/延迟/跟踪/交叉校验全过才算交付 |
| EDR | 在线 O(n_j) 漂移估计 | O(1) | 包络版本变化即重认证；漂移吃裕量即重规划 |
| `G_exact` | Σ cost(精确求值)+包络查表 ≤ τ_g | O(1) | 离线成本认证 + 看门狗；超预算慢模式 |
| CBG+ | cost(⊨)+cost(B,B_v^A,PFL,共识,双哈希) | O(1) | 边界∧屏障∧可行∧PFL∧共识∧双哈希全过才放行 |

**正确性定理（Plan-Scheduled, Actuation-Conditioned, Reactive Soundness）**
假设 (A1)–(A12) 承接 v14；新增：**(A13)** `A_lb(t)⊆A_true(t)` 对经认证的热瞬态/电压跌落/老化包络成立（`M_derate` sound），且 `h(A)` 被守卫强制校验；**(A14)** 关节交付证明以概率 ≥1−α_del 保证 `τ_real` 落在认证包络内，且未检测故障的滞留 ≤ l_max（JDA 看门狗）；**(A15)** 计划骨架 `G` 的每个可达决策/环境节点都有认证出口，及时条件在 `t_boundary−τ_rp` 前成立，且 `τ_rp` 上界被测得、重规划看门狗生效——以概率 ≥1−α_plan。则沿路径、交互序列、步态相位与驱动预算，
`P(∀t≤T: z(t)∈Z_safe) ≥ 1 − Σ_i α_i − Σ_i ε_hand,i − α_lease − α_intent − α_user − α_viable − α_cap − α_act − α_del − α_plan − α_replan − Σ_ℓ δ_{ℓ→d}`；
且**`A_est` 与 `A_lb` 之差、学生提议误差、LFF 假阴性仍不进入安全上界**：它们只提高拒绝率/回退率/保守度（可用性），因为放行要求 `G_exact` 在 `A_lb` 下精确通过且 JDA 交付证明成立。承重点从 v14 的 (A11) 扩为 (A11)∧(A13)∧(A14)∧(A15)：**"证书便宜精确"之外，还必须"包络下界可信、力矩确实交付、退路确实来得及"**。这仍是条件保证：下界模型、交付证明、重规划时延是新的信任锚，由 PFV/LFF/DCL/CCA 的持续证伪、台架标定与真机演练负责，不在定理覆盖范围内。

回退策略：E139 出口漏覆盖 → 拒绝发布该骨架策略、加密决策节点并重分解；E140 下界越界 → 立即收缩 `A_lb`、冻结该 `M_derate` 版本、追加瞬态标定与形式化验证，禁止部署；E141 交付漏检 → 增交叉校验通道、缩短看门狗周期、降级到保护姿态，绝不放松交付判定；E142 捕获不足 → 强制插入散热停留/缩短任务分段/预留更大捕获预算，绝不绕过 `A_lb`；E143 可用性过低 → 改进 `A_est` 与学生覆盖，而非放宽守卫；E144 时延或 MRC 超标 → 缩小共创范围与工作域，绝不绕过 L0/L3.5/精确守卫。

## 6. 本轮最大风险

**一句话**：v15 把 v14 的两条纸面承重梁换成真证书的同时，也新增了三个必须为真的信任锚——`A_lb⊆A_true` 在热瞬态/电压跌落/老化下不越界、JDA 交付证明不漏检未检测故障、重规划在 `t_boundary−τ_rp` 前确实发生；任一下界被瞬态击穿、任一交付被静默失败、或重规划晚于边界，"计划处处有认证出口、证书条件于真实能力"就会退化为"纸面有退路、现实来不及"，因此包络下界必须最坏瞬态标定+形式化验证+持续证伪、交付必须每关节交叉校验+fail-closed、重规划必须实测上界+看门狗+提前缓冲——宁可保守失去可用性，绝不放松。
