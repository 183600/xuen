# 第 42 轮（新循环第 2 轮） · 轮足机器人 × 商业模式：让安全证书成为「可定价、可承保、可审计」的服务合约（五层架构 v7，新增 L5 商业层）

> 承接第 41 轮 v18（CAR × LCS × CMC）。第 41 轮把证书做成了运行时守卫，但它仍活在「安全工程」的世界里——只回答「能不能动」，不回答「值不值得动、由谁买单」。本轮灵感词「轮足机器人」提供了一个**天然的形态学—经济学手柄**：轮/足/混合三态在速度、能耗、地形鲁棒性上本就构成一条风险—成本前沿；「商业模式」则提示把这条前沿包装成**分级服务合约**：证书不再只是安全门，而是**报价单与保单的计量单位**。核心命题：**证书越紧，能承保的风险越低、报价越有竞争力——紧致性第一次有了金钱价值。**

## 0. 直觉与动机

**灵感 1（轮足机器人 → 形态即「风险-成本」旋钮）**：轮足机器人不是「一种」机器人，而是随身携带一个**模式组合（portfolio）**：纯轮态在城市平地上又快又省电，但遇台阶/碎石就危险；足态慢而耗能，却能上楼梯、过废墟；轮足混合态在中间。传统控制把这些模式当作「能力开关」，按地形硬切换。但若从商业视角看，每一个模式其实是**沿风险-成本 Pareto 前沿的一个可交易点**：同一段路，用轮态跑得快、失败概率 p̄_W；用足态跑得慢、失败概率 p̄_L。**选模式=选承担多少风险来换多少毛利**。这正好把第 41 轮「制度（Nominal/Watch/Degraded/SafeStop）」从纯安全的离散档，扩展成带价格标签的连续调度问题。

**灵感 2（商业模式 → 证书是唯一能把「信任」变成「可计价账本」的东西）**：机器人公司卖硬件是一次性生意，卖「可靠的服务」才是复利生意——但客户凭什么相信你的「可靠」？只能靠**可审计的证书**。于是商业模式的直觉是三层递进：
1. **定价**：把认证失败概率上界 p̄ 当作精算输入，报价 ≥ 成本 + 期望赔付，把「糊里糊涂的安全」变成「算得清的保费」。
2. **分级**：同一硬件卖不同 SLA（99% / 99.9% / 99.99%），严格的档必须靠更紧证书（更高档 T2/T3）支撑——**产品分档与证书分档同构**。
3. **认证即服务（CaaS）**：每次执行产出签名证书，串成可审计账本，卖给客户的是「每认证运行小时」的订阅，卖给保险/监管是可验证的理赔凭据。**信任本身成为 SKU。**

**耦合（本轮的关键）**：轮足模式组合给出「成本-风险」前沿，商业模式把它切成「服务档位」，证书则是**唯一被允许在这条前沿上收费的「度量衡」**。三者闭合成一个经济-安全联合调度：业务层想多赚 → 逼证书更紧或模式更稳；证书一旦变松 → 表面利润上升、隐性尾部负债同步上升，最终由审计账本一次性清算。**证书的紧致性由此从「学术指标」变成「毛利率与偿付能力」。**

## 1. 形式化定义

**定义 32（风险-成本服务合约 RCSC）**：合约 C=(ε,T,P,L,D)。ε 为 SLA 允许的失败率上限，T 为任务时域，P 为成交价，L 为单次失败损失（赔付/责任），D 为任务域/地形分布。供方在证书 c 下**可承接**当且仅当 p̄_cert(c,T)≤ε 且 P≥c_exec+L·p̄_cert（偿付约束）。合约的**认证毛利** g=P−c_exec−L·p̄_cert。

**定义 33（轮足形态经济组合 MEMP）**：模式集 M={W,L,WL}（纯轮/纯足/轮足混合），各有成本率 c_m(x)、速度 v_m、认证风险率 λ̄_m(x,j)（j 为证书档）。瞬时认证收益 ρ_m(x,j)=P·v_m−c_m(x)−κ·λ̄_m(x,j)，κ 为风险价格（影子保费）。模式切换有过渡代价 s(m→m′)（能量+暴露时间）且须满足物理可执行性 Feas(m,terrain)。智能体是一个**受证书自动机（IP-51）门控的切换系统**。

**定义 34（证书保真保费 CAP）**：保费 π=(1+η)(c_exec+L·p̄_cert)+η₀，η 为安全边际。**偿付定理**：若证书单边可靠（真实失败概率 p≤p̄_cert）且每单满足 P≥c_exec+L·p̄_cert，则 n 个独立任务累计期望利润≥0；更细地，若 p̄_cert 为 (1−δ_c) 置信上界，则累计赔付以概率 ≥1−δ_c 不超过 L·Σp̄_cert，单期破产概率由 Bernstein 界控制。**推论**：证书相对真值的松弛比 ρ=p̄/p 直接放大所需保费与资本占用——紧致性=资本效率。

**定义 35（认证即服务账本 CSL）**：账本 ℒ 为 Merkle 链，条目 e=(t, x̂, m, m_margin, j, δ_c, task_id, prev_hash, sig)。审计函数 Verify(ℒ) 仅凭签名与单边可靠性检查即可判定「该时段证书成立」，并据此结算理赔。账本对客户/保险/监管**只暴露可验证的界，不暴露原始状态**（可加零知识证明）。

**定义 36（经济-安全联合调度 ESSD）**：策略 π:(x, terrain, C)→(m,j,v)，求解
max E[Σ ρ_m] − 切换代价，s.t. p̄_cert≤ε（SLA 硬约束）、x∈Inv（安全不变式）、m 转移经 IP-51 守卫。
在线版本中 terrain 未知，需**带 SLA 约束的安全探索**：任何探索动作也必须以证书门控。遗憾对 clairvoyant 最优定义。

**定义 37（激励对齐与偿付能力）**：奖励函数分两种：R_cert 仅依赖证书 p̄；R_audit 依赖审计实现 p。**激励不相容命题**：若只用 R_cert，则存在「证书套利」策略使 p̄≤ε 而实现 p>ε、期望收益严格更大（利用 (1−δ_c) 漏洞与模型误差），风险被转移到保单。故必须采用**审计锚定奖励** R_audit（延迟结算），使「卖更便宜的 SLA」必须以「真实更低的失败」兑现。

**设计约束**（在 v6 单调保守性上叠加）：
- (C1) 商业层只能**放宽价格**，不能放宽证书；经济压力永远不能把「不确定」翻译成「更激进模式」。
- (C2) 偿付硬约束：拒绝任何 P<c_exec+L·p̄_cert 的「赔本抢份额」合约。
- (C3) 审计锚定：长期收益与真实审计结果挂钩，封死证书套利。

## 2. 三大产出设计

### 2.1 IP-54 RISK-CONTRACT-ENGINE（风险合约引擎 RCE）
1. 报价：由 p̄_cert 与历史审计得到精算下界 Floor=c_exec+L·p̄_cert；对客户 SLA ε 报 max(Floor, 市场价)；p̄_cert>ε 直接拒单。
2. 分档：SLA 档 ε 与证书档 j 绑定（99%↔T1, 99.9%↔T2, 99.99%↔T3），产品目录自动由证书能力生成。
3. 组合承保：跨任务相关性用 copula/尾部相依估计，避免「看起来独立、灾难时一起违约」。
4. 动态再定价：审计实现 p 与证书 p̄ 的偏差 → 在线校准 η，偏差持续为正则触发模型重证（回写 IP-46）。

### 2.2 IP-55 WHEEL-LEG-ECONOMIC-ARBITRAGE（轮足经济仲裁 WLEA）
1. 模式库：W/L/WL + 每模式的关键参数（c_m, v_m, 地形可行域、认证风险率 λ̄_m）。
2. 证书门控仲裁：对 (m,j) 枚举，丢弃 p̄>ε 或越 Inv 者，在可行集上最大化认证收益。
3. 切换代价与驻留：过渡能量 s、过渡暴露风险、最小驻留 τ_min，防止「为几毛钱反复切换」（经济 Zeno）。
4. 安全探索：地形难度先验未知时，用证书约束的 bandit（只允许风险≤ε 的探索臂），把课程引擎 IP-50 当作「经济课程」。
5. 退化策略：当所有模式都不满足 SLA，回到「最低风险模式 + 最高证书档」，宁可少赚不可违约（承接 v6 可用性守门）。

### 2.3 IP-56 CERTIFIED-SERVICE-LEDGER（认证服务账本 CSL）
1. 执行即签名：每拍/每任务产出证书条目，Merkle 链+签名，防篡改。
2. 审计与理赔：Verify(ℒ) 输出「已验证认证小时」与「认证外事件」，作为计费与理赔唯一依据。
3. 隐私：对外只给区间界与承诺，可附 ZK 证明（状态不外泄仍可核验）。
4. 与 RCE 闭环：账本驱动动态定价与模型重证，形成「证书→合约→审计→证书」的数据飞轮。

## 5. 本轮最大风险

**一句话**：商业模式会把证书从「安全守门员」变成「营销话术」——为了压低报价与抢份额，系统会系统性偏好最低证书档与最激进的轮足模式，把全部隐性尾部风险转移给保单/责任/声誉，一旦尾部事件发生即一次性清算（证书套利→偿付危机）；因此 E83 的审计锚定与 E79 的偿付约束是商业层能否成立的生死门。

## 2. 关键算法（伪代码）

### IP-54 RCE：报价与承保
```
def quote(x, task, cert):
    pbar   = certified_failure_bound(cert, task.T)      # sound upper bound
    c_exec = energy(task, x) + wear(task)
    floor  = c_exec + task.L * pbar                     # 偿付下界
    if pbar > task.eps:
        return REJECT                                   # SLA 不可达
    price  = max(floor / (1 - eta), market_price(task.eps))
    return Contract(eps=task.eps, P=price, L=task.L)

def accept(C, cert):
    pbar = certified_failure_bound(cert, C.T)
    if pbar > C.eps:                     return REJECT  # 安全不可承接
    if C.P < exec_cost(C) + C.L * pbar:  return REJECT  # 偿付硬约束 (C2)
    return ACCEPT
```

### IP-55 WLEA：证书门控的轮足经济仲裁
```
def dispatch(x, terrain, C, cert, prev_mode):
    best = None
    for m in [WHEEL, LEG, HYBRID]:
        if not physically_feasible(m, terrain): continue
        for j in [0,1,2,3]:                              # 证书档
            b    = cert_tier(m, x, j)
            pbar = certified_failure_bound(b, C.T)
            if pbar > C.eps: continue                    # SLA 硬约束
            if not in_invariant(x, b): continue          # 安全不变式
            for v in speed_grid(m):
                profit = C.P*v - c_m(x,v) - kappa*pbar - s(prev_mode, m)
                best = argmax(best, profit, key=(m,j,v))
    if best is None:
        return safest_mode(cert)                          # 单调保守：不违约
    return best
```

### IP-56 CSL：执行即签名 / 审计
```
def emit(entry, prev_hash, sk):
    h = H(prev_hash || entry)
    ledger.append((entry, h, Sign(sk, h)))
    return h

def audit(ledger, auditor_pk):
    settled, violations = 0, 0
    for (e, h, sig) in ledger:
        assert Verify(auditor_pk, h, sig)
        assert one_sided_sound(e)          # ok => 该时段不变式成立
        settled += e.dt                    # 已验证认证小时
    return settled, violations             # 计费/理赔唯一依据
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 正确性保证 |
|---|---|---|
| IP-54 报价 | O(1) 每次（缓存 p̄） | P≥c+L·p̄ ⇒ 单笔期望毛利≥0 |
| IP-54 组合承保 | O(n log n) 排序 + 尾相依估计 | 独立/Bernstein ⇒ 破产概率有界 |
| IP-55 仲裁 | O(\|M\|·\|J\|·\|V\|)，通常 <1ms | p̄≤ε 且 x∈Inv ⇒ SLA 与安全同时满足 |
| IP-55 探索 | 证书约束 bandit，O(臂数) | 任何探索动作亦被证书门控 |
| IP-56 账本 | 追加 O(1)（哈希+签名）；验证 O(1)/条 | 哈希链+签名 ⇒ 篡改可检出；单边可靠 ⇒ 审计可信 |
| IP-52 档位（升级） | 沿用 v18 | 证书档↔SLA 档同构，sound 不破 |
| 全局 | — | 偿付定理：证书越紧 ⇒ 资本占用越低 ⇒ 可承保容量越大 |

## 4. 实验设计（E79–E84，硬门槛）

| 实验 | 指标 | 门槛 |
|---|---|---|
| E79 偿付能力 | 10⁵ 单模拟的破产概率；单位毛利 | 破产<1e-3；毛利>0 |
| E80 轮足仲裁收益 | vs 单模式 baseline 的利润/能耗/成功率 | 成本降≥20%；成功率不降 |
| E81 保费保真 | p̄_cert≥实现 p 覆盖率；校准偏差 | ≥99%；\|偏差\|<10% |
| E82 账本可审计 | 篡改检出率/验证时延/证明大小 | 100%；<10ms；<2KB |
| E83 激励对齐 | R_cert vs R_audit 的尾部事故 | 审计锚定使尾部事故降≥5x |
| E84 端到端商业-安全 | SLA 违约率/可用率/每认证小时收入/灾难事件 | <1%；≥95%；>0；0 起 |

回退路径：E79 不过 → 纯成本定价 + 外部保险；E80 不过 → 固定 Gait；E83 不过 → 提高审计频率/缩短结算周期。

## 5. 风险与缓解

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 证书套利 / 道德风险：压低证书档抢单，隐性尾部风险外溢 | 高 | 审计锚定奖励 (C3)；偿付硬约束 (C2)；尾部相依承保 |
| 证书过松 → 保费失真/资本占用大 | 高 | 沿用 v6 紧致性；p̄ 与实现 p 在线校准；偏差触发重证 |
| 轮足频繁切换（经济 Zeno） | 中 | 切换代价 s + 最小驻留 τ_min + 滞回 |
| 地形未知下的探索破坏 SLA | 中 | 证书约束 bandit；保守先验；退化到最低风险模式 |
| 账本隐私泄露 | 中 | 区间界+承诺；可选 ZK；最小暴露 |
| 相关性被低估（灾难时一起违约） | 中 | copula/尾部相依；压力测试；再保险 |
| 多目标（安全/利润/可用）互相拉扯 | 中 | 分层约束：安全≻SLA≻利润；E84 联合守门 |

## 6. 本轮最大风险

**一句话**：商业层会本能地把证书当成可议价的营销参数——为压低报价而系统性选择最低证书档与最激进的轮足模式，把隐性尾部风险整体转嫁给保单与责任，尾部事件一旦发生即一次性清算（证书套利→偿付危机）；故 E83 审计锚定与 E79 偿付约束是商业层成立的生死门。
