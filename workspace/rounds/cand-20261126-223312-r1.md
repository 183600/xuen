## 1. 两个灵感的第一性原理

### 灵感 1 ·「状态隔离」→ 第 3 轮的单体场景图，该拆成「隔离单元 + 契约」

**直觉**：第 3 轮把状态层做成一张 `SceneState` 单体可变地图，其自报的最大风险是「地图毒化」——一次目标绑定错误顺着整条路标链「自信地失败」。这其实是**架构病**：所有状态挤在一个可变对象里，任何写错都对所有读者可见，污染半径 = 整个系统。状态隔离的直觉答案很朴素：**别把鸡蛋放一个篮子**——把状态拆成有独立置信、独立写者、独立寿命的「单元」，让一次坏写只污染它自己的读者集，并让「不可逆动作」必须经过两条相互独立的状态通道交叉确认。

**严谨定义**：状态单元 `c=(id, scope, schema, owner, readers, lifetime, conf, prov, sync)`（U19）；`owner` 单写者消除并发丢写；`readers` 静态声明污染半径 `ρ(c)`（U20）；读依赖契约图必须是 DAG，禁止经共享可变全局成环。由此得 L14：单体下不可逆错误概率 ≈「任一单元出错」`1−Π(1−ε_c)`；隔离 + 双通道交叉确认（外感通道误差 ε_p、本体通道误差 ε_s 独立）下，不可逆误接受 `≤ ε_p·ε_s`，单单元污染被限制在 `ρ(c)`。**关键工程推论**：双通道必须来自真正独立的传感器（头相机 vs 本体/关节），若两条通道共用同一相机，独立性破裂，乘积界退化为 `min(ε_p,ε_s)`。

- **与第 3 轮的差异**：不是替换 SceneState，而是把它从「单体对象」重构为「单元内核」；`target` / `distractors` / `self(proprioception)` / `task_progress` / `workspace_frame` 各成单元。self 单元近似真值且**永不被外感写者污染**，成为交叉确认的锚。
- **回滚即介入**：IP-02 的介入家族新增「单元回滚」——从上一份 last-known-good 快照恢复某个单元，而不是重启整条路标链（与 L12 的保持-续跑经济学同构）。
- **跨 episode 即隔离破坏**：IP-11 会话记忆本质是「故意打破 episode 隔离」，必须显式、可审计、默认关闭（P15 / IP-19）。

### 灵感 2 ·「多机协同」→ 隔离是默认，协同是「最小共享契约」

**直觉**：多机协同听起来与状态隔离相反，其实是同一枚硬币：**每台机器/每个 agent 本地状态隔离，只共享完成任务所必需的那一点点「契约」**。分布式系统的老经验——共享可变状态是万恶之源，消息传递 + 最小共享 + 确定性合并才可扩展。两台 G1 擦桌子（Two_Robot_Clean_Table_Left/Right）真正需要共享的，可能只是「工作台坐标系 + 区域占用 + 物体归属/交接令牌」，其余全部本地隔离。

**严谨定义**：协同契约 `K=(V, κ, τ, auth, merge)`（U21）：V=共享变量最小集（工作台系 W、区域占用 O、物体归属 C、交接令牌 H）；κ=一致性模型（最终/有界陈旧 Δ/强）；τ=同步节奏；auth=每变量写权限；merge=确定性冲突消解（Lamport 时间戳 + robot-id 字典序）。交接用状态机 U22（IDLE→CLAIM→LOCK→TRANSFER→VERIFY→RELEASE | ABORT），其安全门是 L16 的双机一致性卡方检验：`(x̂_A−x̂_B)ᵀ(Σ_A+Σ_B)⁻¹(x̂_A−x̂_B) ≤ χ²_{d,α_h}`，误中止率 = α_h（U17 的两机推广）。L15 给出「是否值得共享」的经济学：共享净收益 `Δ = 信息增益 − 污染耦合 − 同步时延`，只有高信息/低污染/低频的变量才配进 V（P14）。

- **范围裁决（本轮最重要的一步）**：32 项计分任务全是单机（F1），所以多机协同**不直接加分**。它只有三条可能的正当用途：①作为**辅助训练语料**（双机数据是否提升单机的空间/协作先验）；②作为**评测基础设施**的多机并行（IP-18，直接加速迭代）；③作为**隐藏任务/赛制扩展的期权**（若官方后续加入双机任务）。Q14 要求给出明确决策规则，而不是默认投入。
- **状态隔离先于多机**：先把单机的 SceneState 拆成隔离单元（IP-16），多机契约（IP-17）才有干净的本地状态可隔离；顺序不能反。

## 2. 研究问题（新增 Q13–Q15，接第 1–3 轮 Q1–Q12）

- **Q13（隔离 vs 单体）**：StateCell 隔离相比单体 SceneState，能否可测地降低「污染驱动的失败」？代价（接口复杂度、同步/陈旧延迟、新失效模式如 split-brain）有多大？（E634 / E635 / E638）
- **Q14（多机的范围裁决）**：多机协同不在 32 项计分任务内（F1）——它作为辅助训练、评测基础设施、还是纯负担？给定新双机语料（F4/F5），投入的决策规则是什么？（E636）
- **Q15（多机评测可复现）**：多机分片评测能否与单机结果**逐 episode 位一致**，在提交约束下能拿到多少加速？（E637）

## 3. 设计原则（新增 P13–P15，接第 1–3 轮 P1–P12）

- **P13（隔离优先）**：一切可变状态必须落在单一写者、读者显式声明的隔离单元内；跨单元只经契约读，禁止共享可变全局；契约图必须是 DAG。
- **P14（最小共享）**：跨 agent / 跨机只共享完成协同所需的最小变量集；共享范围与污染代价成反比，按 L15 的边际条件逐变量裁决。
- **P15（可审计的隔离破坏）**：任何跨 episode / 跨 agent 的状态共享都是显式、记录、门控的「隔离破坏」，默认关闭；无静默泄漏（Q9 合规）。

## 4. 清单处置（深化 / 修剪 / 新增）

## 5. 本轮最大风险

**过度工程化一个不计分的维度**：多机协同不在 32 项计分任务内（F1），而隔离重构会引入接口复杂度、同步/陈旧延迟与 split-brain 等新失效模式；若为「多机」付出的隔离/同步成本拖累了真正决定分数的单机成功率，这轮就是把灵感误当需求的典型失败。对冲：IP-18（评测加速）先落地、IP-16 只在单机上验证 L14 的净收益（E634）、IP-17 冻结到 Q14 给出正收益证据为止。**一句话：当前方案的最大风险是——为尚未进入计分任务的多机协同买单的隔离/同步复杂度，可能反噬真正计分的单机成功率。**

## 3. 新增 IP 详述

### IP-16 · StateCell IsolationKernel（P0，新；IP-13 的重构）

- **动机**：v3 的 `SceneState` 是单体可变地图，其最大风险（地图毒化）是架构性的——任何写错对所有读者可见，污染半径=全局。隔离把「全局单点」拆成「局部可降级」。
- **差异**：v3 只有一张图；v4 把状态拆成 `target/distractors/self/task_progress/frame` 五个单元，每个单写者、静态读者集、独立置信与来源、可回滚快照；不可逆动作（抓取闭合、放置释放）前做外感×本体双通道交叉确认（L14）。
- **技术可行性**：高。全部是工程重构，无新模型：单元容器 + 写权限断言 + DAG 读依赖校验 + 快照回滚 + 一个独立性检查。算力不变（仍是低频检测）。
- **资源**：复用 v3 的检测器/跟踪/标注；新增仅是内核代码与单元 schema。接口无新增字段（策略内部）。
- **落地步骤**：①定义五单元 schema 与写者/读者表（DAG 校验）；②内核实现（写权限、污染半径查询、快照/回滚）；③双通道交叉确认接入 IP-02 不可逆动作；④`self` 单元从关节/EE 位姿构造，作为交叉锚；⑤Level-1.7 降级与 E634 污染注入实验；⑥与 IP-09 断言、IP-15 干扰写隔离对接。
- **风险**：单元切分过细 → 接口开销与陈旧；双通道若共用相机 → 乘积界失效（E635 专测）；回滚快照内存/时机（仅对不可逆动作保存，限频）。

### IP-17 · CollaborationContract + HandoffFSM（P2·条件，新）

- **动机**：新双机语料（F4/F5）使多机协同第一次可原型化；但它不在 32 项计分任务内（F1），必须按 Q14 裁决，不能默认投入。
- **差异**：不做端到端多机大模型；只做「本地隔离 + 最小共享契约」：V={工作台系 W、区域占用 O、物体归属 C、交接令牌 H}，确定性合并（Lamport+id 字典序），交接安全门用 L16 双机卡方一致性。近零训练。
- **可行性**：中高（数据完整、协议是工程件）；不确定在「是否值得」（范围/增益）。
- **资源**：Two_Robot_Clean_Table_Left/Right（各 300 ep）+ DualRobot 集合；算力小。
- **步骤**：①从双机回放提取共享变量轨迹（W/O/C/H）与冲突统计；②契约与合并规则实现；③HandoffFSM（U22）与 L16 安全门；④E636 原型 A/B（契约 vs 独立半区）；⑤按 Q14 决策：辅助训练 / 冻结期权 / 进主线。
- **风险**：**范围错配**（不计分却吃资源）；同步/陈旧拖慢单机；双机-单机域差（只作辅助/压力测试，不直接迁移）。

### IP-18 · ShardedBench 多机分片评测（P1，新；纯基建）

- **动机**：「多机」最确定能兑现的价值不是协同操作，而是**把 32 项代理评测并行到多台机器**，直接压缩迭代周期——这是零模型风险的工程护城河。
- **差异**：不是多机器人，而是多计算节点；核心是**逐 episode 种子隔离 + 顺序无关合并**（L17），保证与单机逐 episode 位一致，避免「并行把评测搞飘」。
- **可行性**：高。标准并行 + 确定性种子；无新模型、无新数据。
- **资源**：现有评测栈 + N 台机器/多 GPU；近乎零额外成本。
- **步骤**：①`seed = H(global_seed, episode_id)`，环境/策略各自独立初始化；②worker 只拿 episode 分片，不共享 RNG/env/状态；③合并用 sum/mean 等交换结合归约；④E637 位一致性与加速比；⑤接入 IP-06 日常评测。
- **风险**：隐藏的非确定性（GPU 原子操作、库内 RNG、时间依赖）→ 位一致性失败（E637 门槛，失败即退回单机）。

### IP-19 · IsolationAudit 跨 episode 隔离审计（P1，新）

- **动机**：IP-11 会话记忆与任何跨 episode 共享本质是「隔离破坏」，而 Q9 合规尚未关闭；需要默认关闭、显式开启、全程可审计的闸门，避免静默泄漏既违规又不可调试。
- **差异**：不新增记忆能力，只加「门 + 日志」；把 Q9 从散落在多处的隐忧收敛成一处审计点。
- **可行性**：高（纯工程）。资源近零。
- **步骤**：①定义跨 episode 读写 API（必须显式声明 src/dst/key）；②默认 `enabled=False`，越权即抛 `IsolationViolation`；③开启时写审计日志（时间、键、来源 episode）；④E638 泄漏审计；⑤作为 IP-11 的前置门。
- **风险**：审计开销（仅跨 episode 路径，低频）；把「合法跨 episode 先验」误判为违规（白名单需按 Q9 结论维护）。

## 5. 符号与定义（新增 U19–U22；U1–U18 沿用第 1–3 轮）

- **定义 U19（状态单元）**：`c=(id, scope, schema, owner, readers, lifetime, conf, prov, sync)`；`scope∈{shared, robot-local, episode-local}`；`owner` 为唯一写者；`readers` 为声明的读依赖集；`conf` 为校准置信（含协方差时用 Σ）；`prov` 为来源链；`sync∈{none, push, pull, merge}`。写非 owner ⇒ `IsolationViolation`。
- **定义 U20（污染半径与隔离性质）**：`ρ(c)=` 从 c 出发沿读依赖可达的下游模块集（传递闭包）。隔离性质：读依赖图是 DAG 且 `ρ(c)` 静态有界；不可逆动作必须至少读两个来源独立的单元（双通道）。
- **定义 U21（协同契约）**：`K=(V, κ, τ, auth, merge)`；V 为最小共享变量集；κ 为一致性模型（eventual / bounded-Δ / strong）；τ 同步节奏；auth 每变量写权限；merge 确定性冲突消解（Lamport 时间戳 + robot-id 字典序）。
- **定义 U22（交接状态机）**：状态集 `{IDLE, CLAIM, LOCK, TRANSFER, VERIFY, RELEASE, ABORT}`；`LOCK→TRANSFER` 守卫为 L16 卡方一致性 + 夹爪接触确认；`VERIFY` 失败 → `ABORT` 回 `IDLE`。

```python
# ===== IP-16: 隔离单元 + 内核（单写者 + DAG 读 + 回滚）=====
class Cell:
    def __init__(self, cid, scope, owner, readers, lifetime):
        self.cid, self.scope, self.owner = cid, scope, owner
        self.readers, self.lifetime = set(readers), lifetime
        self.value = self.cov = None
        self.conf = 0.0
        self.prov = []            # 来源链
        self.snapshot = None      # last-known-good

    def write(self, writer, value, cov, conf, prov):
        if writer != self.owner:                       # P13: 单写者
            raise IsolationViolation(self.cid, writer)
        if self.snapshot is None:
            self.snapshot = (self.value, self.cov)
        self.value, self.cov, self.conf = value, cov, conf
        self.prov.append(prov)

    def rollback(self):                                # IP-02: 单元回滚
        if self.snapshot is not None:
            self.value, self.cov = self.snapshot
            self.conf = max(0.0, self.conf - ROLLBACK_PENALTY)


class IsolationKernel:
    def __init__(self):
        self.cells = {}           # cid -> Cell
        self.edges = set()        # (reader, cid) 声明的读依赖

    def declare_read(self, reader, cid):
        self.edges.add((reader, cid))
        if self._has_cycle():                          # P13: 契约图必须 DAG
            raise IsolationViolation("contract-cycle", reader)

    def read(self, reader, cid):
        if (reader, cid) not in self.edges:
            raise IsolationViolation(cid, reader)
        return self.cells[cid]

    def cross_check(self, act):                        # L14: 双通道交叉确认
        p = self.read("exec", "target")               # 外感通道
        s = self.read("exec", "self")                 # 本体通道
        if not independent_sources(p, s):             # 共用相机 → 乘积界失效
            return conservative_gate(p, s, act)       # 退回单通道+保守阈值
        return agree(p, s, act)                       # 不可逆误接受 ≤ ε_p·ε_s
```

## 7. 推导（新增引理 L14–L17；L1–L13 沿用第 1–3 轮）

**引理 L14（隔离界定污染：乘积界）** 设每个状态单元独立出错概率 ε_c。单体可变地图中任一写错对所有读者可见，故不可逆错误概率 ≈ `1−Π_c(1−ε_c)`。隔离后单单元污染限制在 `ρ(c)`；若不可逆动作须外感单元（误差 ε_p）与本体单元（误差 ε_s）**来源独立**地一致，则误接受事件要求两通道同时以相容方式出错，`P(误接受) ≤ ε_p·ε_s`（独立性下；若同向相容进一步降低）。⇒ 隔离把「任一单元错即全局错」变为「两独立通道同时错才不可逆错」，且污染半径从「全部」降到 `|ρ(c)|`。**推论**：通道若共源（同相机），独立性破裂，乘积界退化为 `min(ε_p,ε_s)`——独立性是设计前提而非假设。∎

**引理 L15（隔离-共享经济学）** 设两 agent 共享变量 v 带来任务成功率信息增益 `g(v)`，污染耦合代价 `ε_shared(v)·L`（L=单次污染损失），同步时延代价 `λ·τ(v)`。净收益 `Δ(v)=g(v)−ε_shared(v)·L−λ·τ(v)`。逐变量共享当且仅当 `∂g/∂v > L·∂ε/∂v + λ·∂τ/∂v`。⇒ 共享集合 V 应只含**高信息/低污染/低频**变量；这为 P14「最小共享」提供可计算判据，并解释为何工作台系（强一致、低频、高信息）可共享，而原始像素/连续位姿流（高污染、高频）应本地隔离。∎

**引理 L16（双机交接一致性）** 设两 agent 对交接物体的估计 `x̂_A~N(x,Σ_A)`、`x̂_B~N(x,Σ_B)` 独立。同物 H0 下 `δ=x̂_A−x̂_B~N(0,Σ_A+Σ_B)`，故 `d²=δᵀ(Σ_A+Σ_B)⁻¹δ~χ²_d`，安全门 `d²≤χ²_{d,α_h}` 的误中止率恰为 `α_h`（L11 的两机推广）。异物的检出功效由非中心参数 `μᵀ(Σ_A+Σ_B)⁻¹μ` 单调决定。融合估计用协方差交叉 `Σ_A⊛Σ_B` 以免重复计入共享测量。⇒ 交接安全门可校准，无需逐任务调阈。∎

**引理 L17（分片评测位一致）** 若单 episode 结果 `R=rollout(policy, ep, seed)` 是 `(policy, ep, seed)` 的确定性函数，`seed=H(global_seed, ep.id)` 只依赖全局种子与 episode 身份，worker 只决定「谁跑哪个 episode」而不改变 `seed`，且合并为交换结合归约（sum/mean），则任意 M-worker 的合并结果与单 worker **逐 episode 位一致**。⇒ 满足三条隔离条件（种子隔离、环境/状态不共享、合并顺序无关）即得 `M×` 加速且分数不变；任一条被破坏（共享 RNG、共享 env、顺序相关合并）都会使位一致失败。∎
