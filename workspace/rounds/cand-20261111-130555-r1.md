# 第 55 轮（承接第 54 轮 v16 GroundEdge-GenSim+++；灵感循环第 1 轮；本轮灵感：「热管理」×「伦理与合规」）

> 第 54 轮把技能组合推进到动作空间剖面 `α_S` 与云边双证书 `J=(ρ,A_cert,γ_ce,δ_a)`。但这些对象都隐含一个前提：**动作空间在规划时是静态的，且"动作可行"≈"可以部署"**。本轮用两个灵感词戳破它：**热管理**说明动作空间会随一个慢变、累积、不可逆的物理状态（温度/热债）单调收缩；**伦理与合规**说明存在一类不能与性能做概率交换的硬边界。核心矛盾：H22：热降额（derating）会在任务中途静默侵蚀动作包络，使规划期合法的证书在耐久视界末尾失效；H23：合规若被工程实现为软惩罚，就会与鲁棒性谱一起被"概率预算化"，从硬约束退化为可交易项，形成合规漂移（compliance drift）。

## 0. 直觉与动机

**灵感 1（热是"会被花掉的动作空间"：热降额 = 动作包络的单调收缩）**
直觉：机器人不是"能力恒定"的，力矩、速度、持续算力都被温度约束。热状态 `θ(t)` 慢变、累积、部分不可观；随 `θ` 升高，可用动作集合 `A(θ)` 单调变小。于是第 54 轮的 `α_S(a)` 应升级为 `α_S(a|θ)`，`A_cert` 应带热条件。**热不是运行时的性能损耗，而是对动作空间的前置收缩**——它改变的不是"做得好不好"，而是"还能不能做"。

**灵感 2（热预算与热债：把"续航"从电量扩展到"热耐久"）**
直觉：电池管理只约束能量，热管理约束的是**在耐久视界 `H_th` 内累积的热负载**。定义热债 `D_th` 与热预算 `B_th`，组合规划就变成带资源约束的最短路：路径不仅要动作兼容、鲁棒可行，还要在 `H_th` 内不超热预算。**同一组技能，短时能做完与长时能做完是两种可行性**；热把"组合"从空间问题变成时空问题。

**灵感 3（合规是集合约束，不是惩罚项：伦理盾必须 fail-closed）**
直觉：鲁棒性可以做概率预算（用 `β_E`、`δ_a` 等余量换成功率），但合规不能。合规可容许集 `A_comp = A_phys ∩ A_law ∩ A_eth ∩ A_priv` 是一个**硬边界**：任一动作不在 `A_comp` 内就不许执行，宁可停机（`⊥`）也不许"打个折执行"。因此需要一个独立的 **伦理盾** 算子，把"合规"从奖励函数里的罚项，提升为架构上的过滤层。**合规的失败模式必须是"不可用"，而不是"违规"**——这是与鲁棒性最本质的区别。

**灵感 4（热-合规挤压：两种约束的代数相反，交互出新的失效模式）**
直觉：热是**可花费的累积资源**（能借、要还、慢变量），合规是**不可花费的硬边界**（不能借、不能还、上下文相关）。当热降额把 `A(θ)` 压到与 `A_comp` 相撞，就出现**热-合规挤压**：保合规的动作热不可行，热可行的动作不合规，交集为空。这不是"更难"，而是**无解**。解法不是提高某个阈值，而是结构性的：**伦理热储备 `R_eth`**——在热预算中永久预留一段只给伦理强制动作（避让、急停、求救、让行）使用的裕度，平时不许花；以及 **defer** 作为显式第三态（既非成功也非违规）。

**灵感 5（审计的合规性悖论：为证明合规而记录，记录本身可能违规）**
直觉：合规要可审计，就需要证据链；但记录原始遥测、图像、位置，恰恰可能违反隐私合规——**审计机制本身要合规**。于是审计不能存原始数据，而应存**承诺 + 区间证明**：能证明"当时温度在安全区间、动作在 `A_comp` 内"，却不泄露原始遥测。这把第 54 轮的反向 Explain 通道升级为**可验证合规账本**，且把"自指合规"变成设计约束。

**综合命题**：两个灵感词不是两个补丁，而是两类时间性相反的约束——热=可花费的慢变量（预算/借还），合规=不可花费的硬边界（集合/审计）。本轮核心命题：**可部署性 = 在热预算下沿耐久视界可共可行地满足硬合规边界，并留下可验证证据**。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（热状态与热动作包络）**
热状态 `θ(t) = (T_j, T_m, T_b, SoC, H) ∈ Θ`，含结温、电机温度、电池温度、荷电状态、累积热历史/健康度。热动力学 `θ̇ = f_th(θ, load(a), env)`。技能 `S` 的热条件动作剖面 `α_S(a|θ)`，热动作包络
`A(θ) = { a ∈ A_phys : ΔT_pred(a, θ, h) ≤ ΔT_max }`。
且要求**降额单调性**：`θ_1 ≼ θ_2 ⇒ A(θ_2) ⊆ A(θ_1)`（`≼` 为按温度分量逐项偏序）。

**定义 122（热预算、热债与热耐久视界）**
热预算 `B_th` 为在耐久视界 `H_th` 内允许累积的热负载（温升积分或等效循环数）。热债
`D_th(t) = ∫_0^t (load(τ) − cooling(θ(τ))) dτ`。
计划 `P` **热可行**当且仅当 `∀t∈[0,H_th] : θ(t)∈Θ_safe ∧ D_th(t) ≤ B_th`。热裕度 `m_th(θ) = min_{a∈A(θ)} (ΔT_max − ΔT_pred(a,θ,h))`。**伦理热储备** `R_eth ⊆ B_th` 为只允许伦理强制动作占用的保留额度，常规任务不得侵占。

**定义 123（分层合规动作集与伦理盾）**
合规动作集 `A_comp = A_phys ∩ A_law ∩ A_eth ∩ A_priv`，四层依次为物理安全、法定规则、伦理规范、隐私约束。伦理盾 `Shield_ε : A → A_comp ∪ {⊥}`，`⊥` 表示无合规动作。关键公理（**不可交换性**）：任何证书不得通过收缩 `A_comp` 来提升成功率；`A_comp` 只能整体收紧，不能对单条动作"局部放行"。`Shield_ε` 必须是 **fail-closed** 的。

**定义 124（热-合规共可行性与挤压）**
状态 `θ` 下的共可行裕度
`m_co(θ) = max_{a∈A(θ)} min( slack_th(a,θ), slack_comp(a) )`。
计划 `P` **热-合规共可行**当且仅当 `∀t∈[0,H_th] : m_co(θ(t)) ≥ m_min`。若存在 `t` 使 `A(θ(t)) ∩ A_comp = ∅`（即 `m_co < 0`），称发生 **热-合规挤压**（thermal-compliance squeeze）。

**定义 125（热-伦理联合证书）**
`J_te = (ρ, A_cert, γ_ce, δ_a, θ_0, H_th, B_th, D_th, A_comp, R_eth, C_audit)`，判定域 `dom_{J_te} ∈ {in, out, defer}`：
- `in` 当且仅当 (i) 鲁棒性谱可行；(ii) `∀t, m_co(θ(t)) ≥ m_min`；(iii) `R_eth` 未被侵占；(iv) `C_audit` 完整可验；
- `out` 若 `∃t, A(θ(t)) ∩ A_comp = ∅` 或热预算/储备失败；
- `defer` 若热预测不确定度超界但尚未挤压，或共可行裕度低于预警线——**fail-closed，转人工或收缩任务**。

**定义 126（合规证据链 / 可验证审计账本）**
审计账本 `L = (h_0, …, h_n)` 为哈希链，`h_i = H(h_{i-1} ‖ commit(decision_i))`；`decision_i = (t, θ̂_i, ŝ_i, Shield 判定, 被拒动作与理由, chosen action)`。采用承诺 `commit(·)` 与区间证明，可证明 `θ̂_i` 落在合规区间、动作属于 `A_comp`，而不公开原始遥测。支持 `verify(L, policy)` 与选择性披露 `reveal(L, case)`。**自指合规**：审计机制本身必须满足隐私约束。

## 2. 关键算法 伪代码

### IP-121 TAP（Thermal-Aware Action Profile）

```python
def thermal_action_profile(skill, theta_grid, env, predictor, dT_max):
    alpha = {}
    for theta in theta_grid:
        for a in skill.A_phys:
            dT = predictor.delta_T(skill, a, theta, env)   # 预测温升
            alpha[(a, theta)] = 1.0 if dT <= dT_max else 0.0
    return alpha          # 随 theta 单调收缩的热条件剖面

def derating_envelope(alpha, theta, theta_cov=0.8):
    return {a for (a, th), v in alpha.items()
            if th == theta and v >= theta_cov}
```

### IP-122 TBE（Thermal Budget & Endurance）

```python
def thermal_budget_feasible(plan, theta0, H_th, B_th, thermal_model):
    theta, debt = theta0, 0.0
    for t in range(H_th):
        a = plan.action_at(t)
        theta, heat = thermal_model.step(theta, a)
        debt += heat
        if theta not in Theta_safe or debt > B_th:
            return (False, t, debt)
    return (True, H_th, debt)

def ethical_reserve_ok(plan, theta0, H_th, R_eth, thermal_model):
    # R_eth 只允许伦理强制动作占用，常规任务不得侵占
    return thermal_headroom(plan, theta0, H_th, thermal_model) >= R_eth
```

### IP-123 ECS（Ethical-Compliance Shield）

```python
LAYERS = [safety, law, ethics, privacy]   # 顺序固定：先硬约束后软约束

def ethical_shield(a, ctx):
    for layer in LAYERS:
        verdict = layer.check(a, ctx)      # 只返回 pass/fail/reason
        if verdict.fail:
            return (False, layer.name, verdict.reason)
    return (True, None, None)

def shield_plan(plan, ctx):
    safe = []
    for a in plan:
        ok, layer, reason = ethical_shield(a, ctx)
        if not ok:
            return ('defer', layer, reason)   # fail-closed，绝不放行
        safe.append(a)
    return ('ok', safe)
```

### IP-124 TCF（Thermal-Compliance Feasibility）

```python
def co_feasibility(plan, theta0, H_th, A_comp, thermal_model, m_min):
    theta, warning = theta0, None
    for t in range(H_th):
        A_theta = derating_envelope(plan.skill.alpha, theta)
        margin = hausdorff_margin(A_theta, A_comp)   # 共可行裕度 m_co
        if margin < 0:
            return ('squeeze', t, margin)            # 热-合规挤压
        if margin < m_min and warning is None:
            warning = (t, margin)                    # 提前预警
        theta = thermal_model.step(theta, plan.action_at(t))[0]
    return ('co_feasible', warning, margin)
```

### IP-125 TEC（Thermal-Ethical Certificate）

```python
def thermal_ethical_certificate(plan, ctx, theta0, H_th, B_th, R_eth, m_min):
    ok_b, t_b, debt = thermal_budget_feasible(plan, theta0, H_th, B_th, thermal_model)
    if not ok_b:
        return ('out', 'thermal_budget', (t_b, debt))
    if not ethical_reserve_ok(plan, theta0, H_th, R_eth, thermal_model):
        return ('out', 'ethics_reserve_touched')

    sh = shield_plan(plan, ctx)
    if sh[0] != 'ok':
        return ('defer', sh[1], sh[2])               # 合规不通过即 defer

    co = co_feasibility(plan, theta0, H_th, ctx.A_comp, thermal_model, m_min)
    if co[0] == 'squeeze':
        return ('out', 'thermal_compliance_squeeze', co)
    if co[1] is not None:
        return ('defer', 'co_feasibility_margin', co[1])

    rho = compose_robustness_chain([s.rho for s in plan.skills], K)
    J = JointTE(rho, plan.A_cert, plan.gamma_ce, plan.delta_a,
                theta0, H_th, debt, ctx.A_comp, R_eth)
    J.C_audit = append_audit(plan, theta0, H_th, sh, co)
    return ('in', J)
```

### IP-126 CAV（Compliance Audit & Verifiable Ledger）

```python
def append_audit(prev_hash, decision, commit_key):
    payload = commit(decision, commit_key)          # 承诺，不泄原始遥测
    proof   = range_proof(decision.theta_hat, SAFE_INTERVAL)
    h = H(prev_hash, payload, proof)
    return AuditNode(h, payload, proof)

def verify_ledger(ledger, policy):
    for n in ledger:
        if not verify_range_proof(n.proof, policy.interval): return False
        if n.prev_hash != prev(n).hash:                      return False
    return True
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| TAP | O(|Θ|·|A|·|S|) | O(|Θ|·|A|) | 热预测误差有界、降额单调 |
| TBE | O(H_th·|π|) | O(H_th) | 热模型可步进、预算闭合 |
| ECS | O(|π|·L) | O(1) | 分层 sound、fail-closed |
| TCF | O(H_th·|A|) | O(|A|) | 共可行裕度可计算、预警及时 |
| TEC | O(H_th·|π| + |S|·|A|) | O(|π|) | 三态判定 sound |
| CAV | O(n) append / O(n) verify | O(n) | 承诺绑定性、区间证明 sound |

**正确性定理（Thermal-Ethical Deployability Soundness）**
假设第 53/54 轮 (A22)–(A28) 成立；**(A29)** 热模型误差 `|θ̂−θ|_∞ ≤ ε_th` 且在 `H_th` 上不累积漂移（在线辨识校正）；**(A30)** 伦理盾对 `A_comp` 的编码 sound 且 fail-closed；**(A31)** 审计承诺绑定性 + 区间证明 sound。则：
1. **硬约束零违规**：若 `dom_{J_te} = in` 且执行未被外部打断，则 `P(合规违规 | 执行) = 0`。合规由集合强制，不进入概率预算。
2. **可用性下界**：
`P(可用 ∧ 合规) ≥ 1 − Σ_d(1−ρ_min(d)) − β_E − P(δ_a>Θ_a) − P(compat<θ_a) − P(热模型误差>ε_th) − P(squeeze) − P(audit 不可验)`。
3. **关键区分**：鲁棒性项是**可交换的概率余量**，合规项是**不可交换的集合条件**；`squeeze` 与 `defer` 只降低可用性，不产生违规。若把合规实现为软惩罚，则第 1 条不再成立——上式退化为"用违规换成功率"，定理失效。

## 6. 本轮最大风险

**一句话**：热降额会静默侵蚀合规可容许集，而热动力学与合规语境都慢变且部分不可观，系统可能在纸面上持有"合规证书"、在真实场地却因热状态漂移而实际违规；更危险的是把合规写成软惩罚——那会让整个证书体系变成合规洗白（compliance washing）的装饰，故必须以 **fail-closed 伦理盾 + 伦理热储备 + 视界共可行性 + 独立可验证审计** 四重护栏，宁可停机，绝不把"纸面合规"当作部署前提。

# 第 55 轮产物 · 创新点清单 v32：GroundEdge-GenSim-TE（TAP×TBE×ECS×TCF×TEC×CAV）

> 承接第 54 轮产物 v31。本轮在动作空间剖面与云边双证书之上，增加 **热感知约束层** 与 **硬合规约束层**，并揭示二者交互产生的新失效模式「热-合规挤压」：
> - **TAP（Thermal-Aware Action Profile）**：热条件动作剖面 `α_S(a|θ)` 与单调降额包络 `A(θ)`；
> - **TBE（Thermal Budget & Endurance）**：热预算 `B_th`、热债 `D_th`、耐久视界 `H_th`、伦理热储备 `R_eth`；
> - **ECS（Ethical-Compliance Shield）**：分层硬约束 `A_comp`，fail-closed 伦理盾；
> - **TCF（Thermal-Compliance Feasibility）**：共可行裕度 `m_co` 与挤压判定；
> - **TEC（Thermal-Ethical Certificate）**：三态联合证书 `J_te`（in/out/defer）；
> - **CAV（Compliance Audit & Verifiable ledger）**：承诺 + 区间证明的合规审计账本。
>
> IP 编号：IP-121~IP-126（共 6 个新增）；升级 IP-115/116/119/120 以纳入热状态与合规层。
> 核心观点：**鲁棒性是"可交换的概率预算"，合规是"不可交换的集合约束"**——两者不能放进同一个线性概率预算。

## 2. 关键算法 伪代码

### IP-121 TAP

```python
def thermal_action_profile(skill, theta_grid, env, predictor, dT_max):
    alpha = {}
    for theta in theta_grid:
        for a in skill.A_phys:
            dT = predictor.delta_T(skill, a, theta, env)
            alpha[(a, theta)] = 1.0 if dT <= dT_max else 0.0
    return alpha

def derating_envelope(alpha, theta, theta_cov=0.8):
    return {a for (a, th), v in alpha.items() if th == theta and v >= theta_cov}
```

### IP-122 TBE

```python
def thermal_budget_feasible(plan, theta0, H_th, B_th, thermal_model):
    theta, debt = theta0, 0.0
    for t in range(H_th):
        theta, heat = thermal_model.step(theta, plan.action_at(t))
        debt += heat
        if theta not in Theta_safe or debt > B_th:
            return (False, t, debt)
    return (True, H_th, debt)

def ethical_reserve_ok(plan, theta0, H_th, R_eth, thermal_model):
    return thermal_headroom(plan, theta0, H_th, thermal_model) >= R_eth
```

### IP-123 ECS

```python
LAYERS = [safety, law, ethics, privacy]

def ethical_shield(a, ctx):
    for layer in LAYERS:
        v = layer.check(a, ctx)
        if v.fail:
            return (False, layer.name, v.reason)
    return (True, None, None)

def shield_plan(plan, ctx):
    safe = []
    for a in plan:
        ok, layer, reason = ethical_shield(a, ctx)
        if not ok:
            return ('defer', layer, reason)     # fail-closed
        safe.append(a)
    return ('ok', safe)
```

### IP-124 TCF

```python
def co_feasibility(plan, theta0, H_th, A_comp, thermal_model, m_min):
    theta, warning = theta0, None
    for t in range(H_th):
        A_theta = derating_envelope(plan.skill.alpha, theta)
        margin = hausdorff_margin(A_theta, A_comp)
        if margin < 0:
            return ('squeeze', t, margin)
        if margin < m_min and warning is None:
            warning = (t, margin)
        theta = thermal_model.step(theta, plan.action_at(t))[0]
    return ('co_feasible', warning, margin)
```

### IP-125 TEC

```python
def thermal_ethical_certificate(plan, ctx, theta0, H_th, B_th, R_eth, m_min):
    ok_b, t_b, debt = thermal_budget_feasible(plan, theta0, H_th, B_th, thermal_model)
    if not ok_b:
        return ('out', 'thermal_budget', (t_b, debt))
    if not ethical_reserve_ok(plan, theta0, H_th, R_eth, thermal_model):
        return ('out', 'ethics_reserve_touched')

    sh = shield_plan(plan, ctx)
    if sh[0] != 'ok':
        return ('defer', sh[1], sh[2])

    co = co_feasibility(plan, theta0, H_th, ctx.A_comp, thermal_model, m_min)
    if co[0] == 'squeeze':
        return ('out', 'thermal_compliance_squeeze', co)
    if co[1] is not None:
        return ('defer', 'co_feasibility_margin', co[1])

    rho = compose_robustness_chain([s.rho for s in plan.skills], K)
    J = JointTE(rho, plan.A_cert, plan.gamma_ce, plan.delta_a,
                theta0, H_th, debt, ctx.A_comp, R_eth)
    J.C_audit = append_audit(plan, theta0, H_th, sh, co)
    return ('in', J)
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| TAP | O(|Θ|·|A|·|S|) | O(|Θ|·|A|) | 预测误差有界、降额单调 |
| TBE | O(H_th·|π|) | O(H_th) | 热模型可步进、预算闭合 |
| ECS | O(|π|·L) | O(1) | 分层 sound、fail-closed |
| TCF | O(H_th·|A|) | O(|A|) | 共可行裕度可计算、预警及时 |
| TEC | O(H_th·|π| + |S|·|A|) | O(|π|) | 三态 sound、硬约束不进概率预算 |
| CAV | O(n) append / O(n) verify | O(n) | 承诺绑定、区间证明 sound |

**正确性定理（Thermal-Ethical Deployability Soundness）**
假设第 53/54 轮 (A22)–(A28) 成立；**(A29)** `|θ̂−θ|_∞ ≤ ε_th` 且 `H_th` 内无累积漂移；**(A30)** 伦理盾对 `A_comp` sound 且 fail-closed；**(A31)** 承诺绑定 + 区间证明 sound。则：
```
P(合规违规 | dom_{J_te}=in ∧ 执行) = 0
P(可用 ∧ 合规) ≥ 1 − Σ_d(1−ρ_min(d)) − β_E − P(δ_a>Θ_a)
                 − P(compat<θ_a) − P(热模型误差>ε_th) − P(squeeze) − P(audit 不可验)
```
关键：**合规项是集合条件而非概率余量**；`squeeze`/`defer` 只影响可用性，不改写合规性。把合规写成软惩罚会使定理失效。

## 5. 本轮最大风险

**一句话**：热降额会静默侵蚀合规可容许集，而热动力学与合规语境都慢变且部分不可观，系统可能在纸面上持有"合规证书"、在真实场地却因热状态漂移而实际违规；更危险的是把合规写成软惩罚——那会让整个证书体系变成合规洗白（compliance washing）的装饰，故必须以 **fail-closed 伦理盾 + 伦理热储备 + 视界共可行性 + 独立可验证审计** 四重护栏，宁可停机，绝不把"纸面合规"当作部署前提。
