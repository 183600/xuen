# 第 62 轮（承接第 61 轮「ESEC」IP-173~182；灵感循环第 8 轮；本轮灵感：「视觉语言动作模型」×「成本控制」）

> 第 61 轮用 USR 把场景/意图/阻抗/证据压进共享语义空间，用 MEL 提供零样本物理先验，用 DMS 做执行接地的多轮对话，用 SRT-Dual 解耦语义流与实时流。但它留下四个**成本-动作层面**的硬伤：
> 1. **MEL 只给先验，不给动作**：第 61 轮的输出是 `scene_emb / φ_phys / π_intact`，真正执行仍要靠 EEIS + ERTC 把先验编译成阻抗。**「视觉-语言→动作」的端到端能力缺位**——一旦场景超出预定义特征，先验再准也无法直接生成可执行的动作块。
> 2. **语义锚点是单帧快照，而 VLA 的动作块是时间上的一段**：第 61 轮 `Anchor_t` 只有瞬时语义，无法表达「未来 H 步的动作意图」；VLA 一次推理产出的是 `A=(a_t,…,a_{t+H-1})`，**动作块的时间延展与锚点的瞬时性不匹配**，直接拼接会在块边界产生阻抗/位姿跳变。
> 3. **预算只到「推理频率/Token」，没有到「钱、能量、云」**：第 61 轮 B_mel 能限制调用次数，却不能回答「这次调用值不值 0.03 美元 / 12 焦耳 / 250ms 尾部延迟」；**成本没有价格，就无法做经济学意义上的调度**。
> 4. **没有「该不该算」的第一性决策**：第 61 轮的语义流是固定节拍（10–100Hz）地跑 MEL，**默认「每拍都值得推理」**。真实系统里，最贵的错误不是模型不准，而是**在不该算的时候算了、在该算的时候为了省钱没算**。

## 0. 直觉与动机

### 0.1 先把问题从「模型问题」改写成「经济学问题」

第 61 轮隐含假设：语义推理越强越好。但机器人有硬预算：**每次 VLA 推理都在消耗延迟、能量、金钱、显存和机会**。VLA 不是免费的 oracle，而是一个有价格的「计算服务」。于是本轮的核心问题变成：

> 给定任务预算 B 与风险上限 δ，如何选择**何时调用 VLA、调用哪一档、一次生成多长的动作块**，使任务收益最大、成本可控、安全不退化？

三个决策变量对应三个新机制：**调用时机**（value of computation，VOC）、**调用档位**（model cascade）、**动作块长度**（chunk horizon, H）。三者共同决定「每成功任务成本」（cost per successful task, CPST）。

### 0.2 五个直觉

**灵感 1（视觉语言动作模型 → 动作块策略 VACP）**
直觉：VLA 的正确使用单位不是「一个阻抗点」，而是**一段带语义条件的动作块** `A=(a_t,…,a_{t+H-1})`。动作块同时包含位姿增量、夹爪开合和阻抗参数，天然把「视觉-语言理解」落到「时间上连续的执行」。VLA 的语义头继续给 USR 写 `scene_emb`，动作头则直接产出可执行块。**动作块是成本摊销的天然单位**：一次 200ms 的推理摊到 H 步上，单步成本变成 `C_vla/H`。

**灵感 2（成本控制 → 自适应动作块时域 ACH）**
直觉：动作块越长，单步推理越便宜，但块越「陈旧」，环境一变就危险；越短越跟手，但每步都要推理，贵。于是存在一个**成本-风险最优时域 H***。在「风险随块龄线性增长」的模型下，`H* = sqrt(2 c_0 /(λ_r r_1))`；在「风险随块龄二次增长」时，`H* = (3 c_0 /(2 λ_r r_2))^{1/3}`。**H 不是超参，而是由成本 c_0、风险价格 λ_r、环境变化率 r_1/r_2 共同推导出的量。**

**灵感 3（成本控制 → 把「计算」当成一等动作 CAC）**
直觉：与其固定节拍跑 VLA，不如把「计算」本身建模成动作：`{不调用, 草稿, 验证, 全量 VLA, 云端 VLA}`。每个计算动作有成本、时延、收益。用**约束马尔可夫决策过程（CMDP）**在「成功率 ≥ 目标、风险 ≤ δ、成本 ≤ B」下选动作；拉格朗日乘子 λ 就是「多花一单位成本，允许损失多少任务收益」的**影子价格**。预算松时 λ→0，倾向全量 VLA；预算紧时 λ→∞，退到反应式控制，但**安全盾永远在预算之外独立运行**。

**灵感 4（视觉语言动作模型 → 推测式动作生成 SAG）**
直觉：大部分时刻小策略已经够用，只有少数「分歧大/不确定高」的时刻才需要大 VLA。让小策略先草拟动作块，验证器判断「能否直接执行」；接受则只付小模型的钱，拒绝才调用大 VLA。期望成本 `E[C]=C_d+(1-a)C_v`；若 `C_d=0.05C_v`、接受率 `a=0.8`，则约 **4× 加速**。关键不是省多少钱，而是**用保形预测把「误接受率」压到 δ 以下**——省成本不能省安全。

**灵感 5（合流 → 动作块拼接、预算级联、成本-风险证书与成本对话）**
直觉：VLA 的动作块之间必须**平滑拼接**（否则边界跳变），所以需要重叠混合 + 控制屏障函数（CBF）投影；预算耗尽时必须**分级降级**（云端→机载全量→蒸馏→草稿+验证→缓存/反应式→安全停），且**安全盾与 fallback 不在预算内**；最后用**成本-风险证书 CRC** 把「花了多少、剩多少、风险上界、误接受率、安全盾是否全程在岗」绑成可审计链。若预算不够，DMS 不再硬扛，而是**把成本选项摆到人面前协商**：「便宜但成功率 82% / 贵 0.03 美元但 94% / 中止」。

## 1. 形式化定义（增量：定义 173–185）

**定义 173（VLA 动作块策略 VACP）** 五元组 `V = (ℬ_θ, π_act, h_sem, h_unc, H)`：
- **观测**：`o_t = (I_t, p_t, l, c_t)`，`I_t` 为多视角 RGB-D，`p_t` 为本体感受，`l` 为语言指令，`c_t = (scene_emb, intent_emb, φ_phys)` 为第 61 轮 USR 锚点
- **共享骨干**：`ℬ_θ: o_t → z_t ∈ ℝ^d`
- **动作头**：`π_act(a_{1:H} | z_t)` 输出动作块 `A=(a_1,…,a_H) ∈ 𝒜^H`，其中 `a_i=(Δx_i, Δθ_i, g_i, K_i)`（位姿增量、夹爪、阻抗参数）
- **语义头**：`h_sem(z_t) → (z_scene ∈ ℝ^{d_us}, U_ep, U_al)`，继续写回 USR
- **执行方式**：滚动时域，执行前 `k ≤ H` 步后重规划；`k/H` 为执行比。`k=H` 为开环块，`k=1` 退化为逐帧策略
- **调用成本**：`C_vla(H)=c_0+c_1 H`。扩散/流式动作头 `c_1≈0`（成本主要在去噪步数）；自回归动作 token `c_1>0`（每个动作 token 都要解码）
- **与第 61 轮 MEL 的关系**：MEL 是 VACP 的「先验模式」（只取 `h_sem` 与物理头）；VACP 增加「策略模式」（直接产出动作块）

**定义 174（成本向量与预算）** 一次计算动作 `u` 的成本向量
```
C(u) = (ℓ, e, m, g, n) ∈ ℝ_+^5
ℓ 时延(ms), e 能量(J), m 金钱($), g 显存(MB), n token/FLOPs
```
预算 `B=(B_ℓ,B_e,B_m,B_g,B_n)`；可行 `C(u) ≤ B`（逐分量）。给定影子价格 `λ=(λ_ℓ,λ_e,λ_m,λ_g,λ_n)≥0`，标量成本 `c_λ(u)=λ·C(u)`。定义**每成功任务成本** `CPST = Σ_t C(u_t) / N_success`。关键约定：`B` 中另设**不可挪用的安全储备 `B_safe`**，只用于安全盾/fallback，任何 VLA 调用都不能花它。

**定义 175（自适应动作块时域 ACH）** 设动作块执行到第 `s` 步（块龄）时，单步风险为
```
r(s) = r_0 + r_1 s + r_2 s²
```
则长度 `H` 的平均风险与单步总成本为
```
R̄(H) = r_0 + r_1(H−1)/2 + r_2(H−1)(2H−1)/6
J(H) = (c_0 + c_1 H)/H + c_exec + λ_r · R̄(H)
```
对连续 `H` 求导：
```
线性风险(r_2=0)： H* = sqrt( 2 c_0 / (λ_r r_1) )
二次风险(r_1=0)： H* = ( 3 c_0 / (2 λ_r r_2) )^{1/3}
```
最终 `H_t = clip(round(H*), H_min, H_max)`。注意 `c_1` 只平移成本、不改变最优点的标度；**真正驱动 H* 的是固定开销 c_0 与风险价格 λ_r**。在线用跟踪误差与人工接管率估计 `r_1,r_2`，每 `T_h` 秒重算一次。

**定义 176（成本感知计算控制器 CAC）** 计算动作空间
```
U = {0:reactive, 1:draft, 2:verify, 3:full-VLA, 4:cloud-VLA}
```
状态 `s_t=(U_t, disagreement_t, B_rem_t, deadline_t, R̂_t, task_phase)`。控制器解约束 MDP：
```
max_π  E[ Σ_t γ^t R_t ]
s.t.   E[ Σ_t γ^t C(u_t) ] ≤ B,   P(safety violation) ≤ δ
```
拉格朗日松弛：`L(π,λ)=E[Σ γ^t (R_t − λ^T C(u_t))] + λ^T B`。逐状态选
```
u*(s) = argmax_{u∈U} [ Q_R(s,u) − λ^T Q_C(s,u) ]
λ ← [ λ + η (Ĉ_avg − B) ]_+          # 对偶上升
```
定义**计算价值**：
```
VOC(u|s) = Q_R(s,u) − Q_R(s,0) − λ^T(Q_C(s,u)−Q_C(s,0)) − κ R̂(u|s)
```
仅当 `VOC(u|s) > 0` 才调用该档。λ 的语义是「**为省一单位成本，最多愿意损失多少任务收益**」：λ→0 时全量 VLA，λ→∞ 时退到反应式，但安全盾不受 λ 影响。

**定义 177（推测式动作生成 SAG）** 草稿策略 `π_d` 产出 `A_d`，验证器 `V_φ` 给接受分
```
α(A_d,s) = P( safe ∧ task-consistent | s, A_d )
接受 ⇔ α ≥ τ
```
期望成本与加速比：
```
E[C] = C_d + (1−a) C_v,   a = P(α ≥ τ)
S = C_v / E[C] = 1 / ( C_d/C_v + 1 − a )
```
若 `C_d=ρ C_v`，则 `S=1/(ρ+1−a)`。误接受率用保形风险控制校准：
```
FAR(τ) = P(V=1, unsafe | α ≥ τ)
τ̂ = min{ τ : UCB_{δ_c}(FAR(τ)) ≤ δ }
```
在可交换性假设下，`P(unsafe | accept) ≤ δ`（置信度 `1−δ_c`）。被拒绝的块交给全量 VLA；无论接受与否，**安全盾始终最后一道**。

**定义 178（动作块平滑与屏障 ABS）** 旧块 `A^old`、新块 `A^new`，重叠窗 `W`，混合权重 `w_t=smoothstep((t−t_0)/W)`：
```
ã_t = w_t a_t^old + (1−w_t) a_t^new
a_t^safe = argmin_{a∈𝒜_safe(c_t)} ||a−ã_t||²_W
CBF： h(a_{t+1}^safe) ≥ (1−γ) h(a_t^safe)
```
若 `𝒜_safe=∅` 或投影不可行：`a_t^safe ← a_last_safe`，并向 DMS 发「语义-物理冲突」澄清。连续性界：
```
||a_{t+1}−a_t|| ≤ max(L_old,L_new) + (Δ/W)·||a^old−a^new||
```
即块边界跳变随 `1/W` 衰减；硬切（`W→0`）时退化为 `O(diam(𝒜))` 的跳变。这是对第 61 轮「语义锚点切换导致阻抗跳变」的机制性修复。

**定义 179（预算感知级联降级 BCD）** 性能档位
```
L0 云端 VLA  → L1 机载全量 VLA → L2 蒸馏 VLA
→ L3 草稿+验证 → L4 缓存/反应式 → L5 安全停
```
每拍在「价格可承受」的档位中选效用最大者：
```
u* = argmax_{u : C(u) ≤ B_rem − B_safe} [ p̂_success(u) − λ^T C(u) − κ R̂(u) ]
若无可行 u： u = L5
B_rem ← B_rem − C(u*)
```
**安全不降级原则**：`B_safe` 与安全盾/fallback 永远保留；预算耗尽只降低「智能档位」，绝不降低「安全档位」。

**定义 180（PCE++++++ 八维认知-经济预算）** 在第 61 轮六维预算上增加 VLA 与经济学维度：
```
B_cog8 = (B_scene, B_intent, B_ros, B_exec, B_usr, B_vla, B_econ, B_safe)
B_vla  = (Token_budget, FLOPs_budget, Latency_budget, ODE_steps, H_max)
B_econ = (Money_budget, Energy_budget, Egress_budget, Thermal_budget)
B_safe = (Risk_budget, Fallback_reserve)        # 不可被 VLA 调用消耗
cost_cog8 = λ_scene·Rec + λ_intent·Lat + λ_ros·Msg + λ_usr·Align
          + λ_vla·(Tok/Tok_max + FLOPs/FLOPs_max + ℓ/ℓ_max)
          + λ_econ·(m/m_max + e/e_max)
voi_cog8 = VOI_meta − cost_cog8 − λ_r·R̂
```
降级顺序：减 H → 减采样/去噪步 → 蒸馏 → 草稿+验证 → 缓存/反应式 → 安全停；**任一步都不移除安全盾**。

**定义 181（成本-风险证书 CRC）** 现场可审计的成本凭证：
```
J_cost = (J_sem_exec, tier_trace, H_t, C_t, B_rem_t,
          R̂_UCB, FAR_UCB, λ_t, shield_attest, trace_hash)
Valid(J_cost) ⇔ Valid(J_sem_exec)
  ∧ C_t ≤ B_t (逐分量)
  ∧ R̂_UCB ≤ δ
  ∧ FAR_UCB ≤ δ
  ∧ shield_attest = true          # 每个执行动作都经过安全盾
  ∧ tier_trace 不含未授权的跳档
  ∧ p99(latency) ≤ L_max
```
其中 `R̂_UCB`、`FAR_UCB` 用保形/Clopper–Pearson 上界，**禁止用均值冒充风险上界**。λ_t 一并入证，使「为什么这个任务花了这么多」可解释。

**定义 182（成本对话协商 CDN）** 扩展第 61 轮 DMS 的动作集：
```
A_cost = {ask_budget, offer_tier, negotiate_cost, accept_tier, abort}
```
当预测成本超预算或风险超阈值，DMS 给出 Pareto 选项菜单 `{o_i}`，每个选项带 `(p̂_success, m̂, ℓ̂, R̂)`，用户可选择/修改预算。对话效用：
```
U(o) = p̂_success(o) − λ_m m̂(o) − λ_r R̂(o) − λ_ℓ ℓ̂(o)
```
这使「成本控制」从后台调度变成**人机可协商的显式契约**。

**定义 183（成本弹性闭环 CEL）** 第 62 轮主循环：
```
CEL(M, o_t, l, B):
  c ← USR.read_anchor()
  # 1) 估成本/风险，选计算档位
  u ← CAC.select(s_t, B_rem)
  # 2) 生成动作块（草稿/验证/全量）
  if u in {draft, verify}: A, alpha ← SAG.propose(o_t,l,c)
  if alpha < τ or u in {full,cloud}: A ← VACP.sample(o_t,l,c,H_t)
  # 3) 拼接 + 安全投影 + 实时执行
  A_safe ← ABS.blend_and_project(A, A_prev, c)
  for k in 1..H_t:
      execute(A_safe[k]); EV_exec ← wait_contact()
  # 4) 账本、学习、证书
  B_rem ← B_rem − C(u); update(r_1,r_2); λ ← dual_ascent()
  M.USR.update(VACP.h_sem); M.DMS.ground(EV_exec)
  J_cost ← build_cost_cert(M.J_sem_exec, u, H_t, C, B_rem, R̂_UCB, FAR_UCB, λ, shield_attest)
  if not Valid(J_cost): BCD.degrade() ∨ CDN.negotiate() ∨ safe_stop()
  return A_safe, J_cost
```

**定义 184（成本-价值前沿 CVF）** 对策略/调度 π，取其非支配点
```
F = { (CPST(π), success(π), risk(π)) : 不存在 π' 在三项上均不差且至少一项更优 }
预算最优： π*(B) = argmax_π success(π)  s.t. CPST(π) ≤ B, risk(π) ≤ δ
```
用超体积（hypervolume）或「达到目标成功率的边际成本」比较不同方法；**不看单点最优，而看整条前沿**。

**定义 185（成本弹性部署包络 CED）** 落地声明：
```
E_cost = (T, Z, H, B, L_max, E_max, M_max, S, ρ_min)
In-Envelope(x) ⇔ x∈T×Z×H ∧ 资源约束满足 ∧ Valid(J_cost;x)
```
对包络内任意 `x`，要求 `P(Valid(J_cost)) ≥ 1−δ`。**出包络 ⇒ 降级 / 协商 / 拒绝执行**，而不是悄悄失效。这把「省成本的研究 demo」与「可交付的成本可控系统」区分开。

## 2. 关键算法伪代码

### IP-183 VACP（动作块策略）

```python
class CostAwareVLA:
    def __init__(self, backbone, d_us=256, H_max=16):
        self.backbone = backbone          # 视觉-语言-本体共享骨干
        self.action_head = ActionChunkHead(H_max)
        self.sem_head = SemanticHead(d_us)
        self.unc_head = UncertaintyHead()
        self.H_max = H_max

    def sample_chunk(self, o, l, c, H, N_ode=8):
        z = self.backbone(o, l, c)
        # 扩散/流式动作头：N_ode 步去噪；自回归头则逐 token 解码
        A = self.action_head.sample(z, H=H, steps=N_ode)   # (H, d_a)
        U = self.unc_head(z)
        z_scene = self.sem_head(z)
        cost = self.cost_model(H, N_ode, len(l))
        return A, z_scene, U, cost
```

### IP-184 ACH（自适应时域）

```python
def optimal_horizon(c0, c1, lam_r, r1, r2, H_min=2, H_max=16):
    if r2 <= 1e-6 and r1 > 1e-6:
        H = math.sqrt(2.0 * c0 / (lam_r * r1))          # 线性风险
    elif r2 > 1e-6:
        H = (3.0 * c0 / (2.0 * lam_r * r2)) ** (1.0 / 3) # 二次风险
    else:
        H = H_max
    return int(min(H_max, max(H_min, round(H))))
```

### IP-185 CAC（成本感知计算控制器）

```python
class CostAwareComputeController:
    def __init__(self, cost_model, risk_model, eta=0.01):
        self.cost_model, self.risk_model = cost_model, risk_model
        self.lam = np.zeros(5)          # 影子价格
        self.eta = eta

    def voc(self, s, u):
        gain = self.q_reward(s, u) - self.q_reward(s, 0)
        cost = self.cost_model(u) - self.cost_model(0)
        risk = self.risk_model(s, u)
        return gain - self.lam @ cost - self.kappa * risk

    def select(self, s, B_rem):
        feasible = [u for u in U if self.cost_model(u) <= B_rem - B_safe]
        if not feasible:
            return U_SAFE_STOP
        return max(feasible, key=lambda u: self.voc(s, u))

    def dual_update(self, c_avg, B):
        self.lam = np.maximum(0.0, self.lam + self.eta * (c_avg - B))
```

**正确性定理（CEL-Sound）**：
假设 **(A71)** VACP 对条件与动作 Lipschitz 连续，动作块误差有界；**(A72)** 成本模型是真实成本的保守上界（校准误差 `ε_cost`）；**(A73)** 风险模型 `r(s)` 是块龄风险的上界；**(A74)** 安全盾健全：可行时投影满足 CBF/ERTC，不可行时回退到 `a_last_safe`；**(A75)** 验证器校准集与在线分布可交换；**(A76)** `B_safe` 与安全盾不在 VLA 预算内；**(A77)** 对偶上升在有界梯度下收敛到 `λ*` 的 `ε_λ`-邻域。

则：
1. **成本-时域最优性**：`H*` 最小化 `J(H)` 的上界；整数 `H_t` 的次优性 ≤ `O(c_0/H*²)`。
2. **预算可行性**：采用保守成本上界与 `B_safe` 预留时，`Σ C(u_t) ≤ B − B_safe`；若使用对偶更新，则期望成本 ≤ `B + O(1/√T)`。
3. **安全与成本解耦**：无论 VLA 多贵、预算多紧、动作块多不準，执行动作始终经过安全盾；预算耗尽只降智能，不降安全。
4. **推测安全性**：若验证器保形校准有效，则 `P(unsafe | accepted) ≤ δ`；被拒绝的块退回全量 VLA 或安全停。
5. **拼接连续性**：重叠混合 + 投影后的块边界跳变 ≤ `max(L_old,L_new) + (Δ/W)||A^old−A^new||`，不产生硬切。
6. **证书可靠性**：`Valid(J_cost)` ⇒ 成本不超预算、风险上界 ≤ δ、安全盾全程在岗，三者同时成立。

## 3. 关键推导：动作块时域 H*

设一次 VLA 调用的固定成本为 `c_0`，每步动作的边际成本为 `c_1`；执行 `H` 步后重规划。块龄 `s` 的风险取线性 `r(s)=r_0+r_1s`，则
```
J(H) = c_0/H + c_1 + c_exec + λ_r [ r_0 + r_1(H−1)/2 ]
dJ/dH = −c_0/H² + λ_r r_1/2 = 0
⇒ H* = sqrt( 2 c_0 / (λ_r r_1) )
```
若风险二次增长 `r(s)=r_0+r_2s²`，则 `R̄(H)≈r_0+r_2H²/3`，
```
dJ/dH = −c_0/H² + (2/3)λ_r r_2 H = 0
⇒ H* = ( 3 c_0 / (2 λ_r r_2) )^{1/3}
```
**读法**：`c_0` 越大（模型越贵），越应该「一次多算几步」；`λ_r r_1` 越大（环境变化快/风险价格高），越应该「少算快换」。这解释了为什么同一 VLA 在静态桌面任务上 H 可以取 16–32，而在动态抓取上只能取 4–8。

| `λ_r r_1`（归一化） | 0.005 | 0.010 | 0.020 | 0.040 |
|---|---:|---:|---:|---:|
| `H*`（`c_0=1`） | 20 | 14 | 10 | 7 |
| 适用场景 | 静态装配 | 桌面抓取 | 动态避障 | 人机共融 |

### 5.1 VACP + CEL 主循环

```python
class CostAwareVLAExecutor:
    def __init__(self, vla, draft, verifier, shield, ctrl, budget):
        self.vla, self.draft, self.verifier = vla, draft, verifier
        self.shield, self.ctrl, self.budget = shield, ctrl, budget
        self.prev_chunk = None

    def step(self, o, l, c):
        s = self._state(o, c)
        u = self.ctrl.select(s, self.budget.rem)
        H = optimal_horizon(self.budget.c0, self.budget.c1,
                            self.budget.lam_r, s.r1, s.r2)

        cost = 0.0
        if u in (DRAFT, VERIFY):
            A_d, cd = self.draft.propose(o, l, c, H)
            alpha = self.verifier.score(o, l, c, A_d)
            cost += cd
            if alpha < self.budget.tau:
                A, cv, z_sem, U, cvla = self.vla.sample_chunk(o, l, c, H)
                cost += cvla
            else:
                A = A_d
        else:
            A, cv, z_sem, U, cvla = self.vla.sample_chunk(o, l, c, H)
            cost += cvla

        A_safe, conflict = blend_and_project(self.prev_chunk, A, c, W=8)
        if conflict:
            self.dms.negotiate_semantic_conflict(c, A_safe)

        for a in A_safe:
            self.ertc.dispatch(a)
            ev = wait_contact()
            self.usr.update(z_sem, ev)

        self.prev_chunk = A_safe
        self.budget.spend(cost)
        self.ctrl.dual_update(self.budget.c_avg, self.budget.B)
        cert = build_cost_cert(self.usr.cert, u, H, cost,
                               self.budget.rem, self.risk_ucb,
                               self.far_ucb, self.ctrl.lam,
                               self.shield.attest)
        if not valid(cert):
            self.bcd.degrade_or_stop()
        return A_safe, cert
```

### 5.2 CAC（计算价值门控 + 对偶上升）

```python
class ComputeController:
    def __init__(self, q_reward, cost_model, risk_model, kappa=1.0, eta=0.01):
        self.q_reward, self.cost_model, self.risk_model = q_reward, cost_model, risk_model
        self.kappa, self.eta = kappa, eta
        self.lam = np.zeros(5)

    def voc(self, s, u):
        gain = self.q_reward(s, u) - self.q_reward(s, REACTIVE)
        dc = self.cost_model(u) - self.cost_model(REACTIVE)
        return gain - self.lam @ dc - self.kappa * self.risk_model(s, u)

    def select(self, s, B_rem):
        feasible = [u for u in U if self.cost_model(u) <= B_rem - B_SAFE]
        if not feasible:
            return SAFE_STOP
        return max(feasible, key=lambda u: self.voc(s, u))

    def dual_update(self, c_avg, B):
        self.lam = np.maximum(0.0, self.lam + self.eta * (c_avg - B))
```

def calibrate_tau(scores, unsafe, delta=0.05, delta_c=0.05):
    # scores: 验证器接受分；unsafe: 是否真的不安全
    order = np.argsort(-scores)
    best = 1.0
    for k in range(1, len(scores) + 1):
        sel = order[:k]
        far = unsafe[sel].mean()
        ucb = clopper_pearson_upper(unsafe[sel].sum(), len(sel), delta_c)
        if ucb <= delta:
            best = scores[sel].min()

            break
    return best

def speculative_step(draft, verifier, vla, o, l, c, H, tau):
    A_d, cd = draft.propose(o, l, c, H)
    alpha = verifier.score(o, l, c, A_d)
    if alpha >= tau:
        return A_d, cd, True
    A_v, cv = vla.sample_chunk(o, l, c, H)

### 5.4 ABS + CRC（拼接与证书）

```python
def blend_and_project(A_old, A_new, c, W=8):
    if A_old is None:
        return A_new, False
    out = []
    for i, a_new in enumerate(A_new):
        w = smoothstep(min(1.0, i / W))
        a = w * A_old[min(i, len(A_old)-1)] + (1 - w) * a_new
        a_safe = shield.project(a, c)
        if not shield.feasible(a_safe, c):
            return [shield.last_safe()] * len(A_new), True
        out.append(a_safe)
    return out, False

        R_ucb=R_ucb, FAR_ucb=FAR_ucb, lam=lam,
        shield_attest=shield_ok, trace_hash=hash_trace())
```

### 5.5 BCD（预算级联）

```python
def cascade_select(s, B_rem, tiers):
    # tiers 按 L0..L5 排列；cost/risk/success 均为当前状态估计
    feasible = [t for t in tiers if t.cost(s) <= B_rem - B_SAFE]
    if not feasible:
        return SAFE_STOP
    return max(feasible, key=lambda t: t.success_hat(s)
                                       - lam @ t.cost(s)
                                       - kappa * t.risk_hat(s))
```

## 6. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性/保证 |
|---|---|---|---|
| VACP | O(Hd² + N_ode Hd) | O(Hd) | 动作块成本上界 |
| ACH | O(1) | O(1) | H* 为连续松弛最优；整数误差 ≤ 1 |
| CAC | O(|U|) / 拍 | O(1) | 对偶间隙 O(1/√T)（标准 CMDP 假设） |
| SAG | O(Hd) | O(Hd) | 保形 FAR ≤ δ |
| ABS | O(Hd + QP) | O(Hd) | CBF 可行 ⇒ 安全；跳变 O(1/W) |
| BCD | O(|tiers|) | O(1) | 预算不超支；安全不降级 |
| PCE++++++ | O(1) | O(1) | `B_safe` 不可挪用 |
| CRC | O(1) | O(1) | 成本/风险/安全联合可审计 |
| CEL | O(1) 额外 | O(1) | 失败可回滚 L5 |

**定理（CEL-Sound，摘要）**：在 A71–A77 下，
1. `H*` 最小化 `J(H)` 上界，整数解次优性 `O(c_0/H*²)`；
2. 保守成本上界 + `B_safe` 预留 ⇒ `ΣC ≤ B−B_safe`；对偶更新期望成本 `≤ B+O(1/√T)`；
3. 安全盾独立于预算 ⇒ 任何档位/预算下执行动作满足 CBF/ERTC；
4. 保形验证器 ⇒ `P(unsafe|accepted) ≤ δ`；
5. 重叠混合 + 投影 ⇒ 块边界跳变 `≤ max(L_old,L_new)+(Δ/W)||A^old−A^new||`；
6. `Valid(J_cost)` ⇒ 成本、风险、安全三项同时成立。

## 8. 成本-价值前沿与部署

**前沿点（示例，归一化 CPST，越低越好）**：
```
全量 VLA 每拍：   CPST=1.00, success=0.91, risk=0.02
固定 10Hz：       CPST=0.74, success=0.87, risk=0.03
CEL（本方案）：   CPST=0.56, success=0.89, risk=0.02
纯反应式：        CPST=0.18, success=0.61, risk=0.06
```
**读法**：CEL 不是「最便宜」，而是在给定风险下把前沿往外推；纯反应式虽便宜但成功率塌陷，说明「成本控制」不能只看成本轴。

**部署包络 `E_cost`**：
- **Tier-0/1**：MCU/NPU 常驻，反应式 + 草稿，`<10ms`；
- **Tier-2**：机载 GPU，全量 VLA，`~120ms`，按需唤醒；
- **Tier-3**：云端，仅在网络稳定、隐私允许、预算充足时启用；
- **监控**：影子上线（学生 vs 教师）、成本漂移、接受率漂移、λ 重标定、FAR 复检；
- **回滚**：`CPST` 超预算、`FAR_UCB>δ`、`R̂_UCB>δ` 或安全事件 ⇒ 降档/回滚 L5。

## 9. 本轮最大风险

**一句话**：若成本模型低估 VLA 的尾部时延/能耗/云费用，或验证器在分布外把「看起来安全」的草稿动作误接受，成本控制器会把系统推向「便宜但危险」的角落——**用预算约束悄悄换掉了安全边际**；必须以「成本上界而非均值 + 安全盾独立于预算 + 保形误接受率控制 + 影子模式在线校准」保证降本永不降安全。
