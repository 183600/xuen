# 第 1 轮（新灵感循环：视觉问答 × 步骤分；基线 v16）

> **基线**：第 14 轮 MetricVoiceGauge-NCD-HUTDH-v16（定义 627–656；引理 131–136；实验 E671–E690）。
> 本轮纪律：**感知接地为前置、步骤信用为价值、证书搜索为节拍**。不推倒 v16：v16 的 BTS/TRM/WBC/CSC/NCS/MCA/WCB、v15 的 SCD/DSD/DCA/EDC、v13–v6 与历轮不变式全部保留。三个新组件——GCE（接地证书引擎）、SCC（步骤信用证书）、SCGS（步骤分引导的证书搜索）——一律以**中立元**接入，失效即严格退回 v16（引理 137），再沿 v16→v15→v14→v13→v12→v11→v10→v9→v8→v7→v6 退化链退回。本轮只做三件事：把"视觉问答"改写为**带接地证书的前置算子**、把"步骤分"改写为**不可跨合取求和的瓶颈信用证书**、把"分步搜索"改写为**只重排可行域、不扩张授权**的单调证书搜索。

## 0. 直觉与动机

**灵感 1（视觉问答 → 接地证据证书，而不是答案正确率）**
直觉：v16 的证书覆盖了时限、动力学、数据覆盖，却默认观测 `x` 可信；VQA 恰好卡在最前端。机器人问"我面前是不是可抓取的杯子"，真正要证的不是"答案对不对"，而是"图中哪块区域、以何证据、能否推出这个答案"。一个自信但错误的 VQA，会让错误的地面化区域**直接穿过所有下游证书**——下游每一步都合法，整条链却建立在幻觉上。核心创新：**接地证书引擎（Grounding Certificate Engine, GCE）+ 接地证书 GVC**。给定图像 `I`、问题 `q`，输出答案 `a` 以及 `GVC(I,q,a)=(R, V, τ, α, η)`：区域集 `R`、证据视图集 `V`、蕴涵统计量 `τ`、共形水平 `α`、接受阈值 `η`。只有 `R` 非空、在视角扰动下稳定、且蕴涵下界 `L_g ≥ η` 时答案才被接受，否则落入 `{SUPPORTED, UNDETERMINED, CONTRADICTED}` 的后两者。关键反直觉点：**VQA 进入安全回路后，"拒答"是一等公民**——UNDETERMINED 必须路由到保守分支，而不是被 softmax 置信度掩盖；"拒答"不是能力缺陷，而是证书系统的正常输出。

**灵感 2（步骤分 → 瓶颈信用证书，而不是可相加的奖励）**
直觉：长程具身任务的二值 SUCCESS 太粗——做到 80% 也有价值，但"80% 的价值"绝不能与"完成"混为一谈。数学推理中的过程奖励模型（PRM）给出稠密步骤分，可一旦直接拿来当奖励，就给奖励黑客留了门：把十个各 0.9 的**未完成**子步骤相加，就能伪装成"完成"。核心创新：**步骤信用证书（Step-Credit Certificate, SCC）**。每一步携带 `(σ_low, σ_up, credit_map)`，`σ_low` 是朝 `Post` 推进比例的共形下界；复合节点用**瓶颈代数**合成：Sequence 取 `min`（短板决定进度）、Selector 取 `max`、Parallel(k/m) 取第 k 阶统计量、Decorator 只能收缩信用。关键反直觉点：**信用是"瓶颈"不是"积分"**——跨合取步骤禁止求和；聚合信用必须 ≤ 真实完成度 + 已认证间隙 `γ_gap`；完成仍由 `Post` 证书结算，而不是由信用高低结算。稠密信号只能改变"先做哪一步"，不能改变"算不算做完"。

**灵感 3（VQA × 步骤分 × v16 → 接地步骤证书搜索）**
直觉：v16 的 CSC 在 `(tick 预算, 里程碑, WBC 阶层)` 上做单调退化，价值函数 `val(n)` 是手设计的。现在把价值换成**已校准的步骤信用**，把前置换成**接地证书**，搜索就变成：按 `σ_low` 降序做步骤级 beam search，凡接地为 UNDETERMINED/CONTRADICTED 的分支一律剪除，凡信用高但 `Post` 未证的节点只算 RUNNING（可银行、不可结算）。核心创新：**步骤信用引导的证书搜索（Step-Credit Guided Search, SCGS）**。SCGS 只做两件事：**重排**（在已可行集合里按信用排序）与**剪枝**（删除接地不成立的分支），绝不放宽任何授权；因此 `Exec_v17 ⊆ Exec_v16`。关键反直觉点：**步骤分越有用，越不能给它授权**——它的全部价值来自"在安全集合内部做更好的排序"，一旦它被允许解锁任何东西，洗白风险立刻出现。

**三者如何统一**
统一为 **v16 行为层之上的"感知—信用"层**：v16 回答"当前证书下能安全执行哪个全身行为"（`Exec_v16`），v17 回答"机器人能声称自己看见了什么、到目前为止可证的进度是多少，据此该 tick 哪一步"（`Exec_v17`）。GCE 把观测变成带证据的接地证书，SCC 把执行路径变成带瓶颈信用的进度证明，SCGS 用二者在 v16 的可行域内重排与剪枝。共享状态 `ζ_vqa=(GVC_stack, σ_vector, credit_ledger, grounding_mode, laundering_flag, mode_vqa)`。**GCE 管"看见的证据是否成立"，SCC 管"进度是否可证"，SCGS 管"下一步做什么"，v16 的 CSC 仍管"在什么预算与模型下退化"**。四者不是四个补丁，而是"接地—进度—搜索—执行"的感知信用链。

## 1. 研究问题（轮次升级版）

- **Q1（接地证书的共形有效性）**：如何为 VQA 定义在视角扰动、分布漂移、组合式提问下仍保持共形有效性的 `GVC`？多跳问题的子证书合取会破坏交换性吗？`UNDETERMINED` 如何严格路由到 `Pre` 的保守分支而不引入活锁？
- **Q2（步骤信用的校准与代数）**：如何把 PRM/标注者给出的稠密步骤分校准成 `SCC` 的共形下界？Sequence/Selector/Parallel/Decorator 的瓶颈信用代数如何保证单调、保守、不可洗白？中断时信用如何"银行化"但不"结算"？`γ_gap` 如何认证？
- **Q3（接地步骤搜索的可行域与最优性）**：SCGS 如何只重排/剪枝而不扩张可行域？接地与信用双约束下的 Pareto 前沿如何刻画？beam 宽度 `W` 与实时预算如何权衡？频繁重排导致的行为抖动如何抑制？
- **Q4（退化与累计风险）**：GCE/SCC/SCGS 失效时能否严格退回 v16？步骤信用能否在 `Post` 不成立时被"误接"为里程碑解锁条件？v17 叠加 v16–v6 证书栈后下界是否衰减到只剩 Fallback？

## 2. 设计原则（在 P25–P27 基础上新增 P28–P30）

**P28 接地即前置证书律（Grounding as Pre-Certificate）**
VQA 答案 `a` 仅在 `GVC` 成立时可进入 Action 节点的 `Pre`。`GVC` 只能**收紧** `Pre`：`Pre_v17 = Pre_v16 ∩ {x : GVC(I_x, q, a_x) = SUPPORTED}`。`UNDETERMINED`/`CONTRADICTED` 必须走 `Fallback`，禁止以连续置信度替代三值判定。任何多个答案的择一由 `Selector` 承担，但每个分支各自携带独立 `GVC`，禁止用"平均置信度"合成一个接地证书。

**P29 步骤分即瓶颈信用律（Step Score as Bottleneck Credit）**
`SCC` 必须是完成度的**共形下界**：`σ_low ≤ E[progress | step]`（高概率）。复合信用用瓶颈代数 `Φ`：`Φ_seq=min`、`Φ_sel=max`、`Φ_par=k-th order statistic`、`Φ_dec=shrink`。禁止跨合取求和：`Credit(Sequence) ≤ min_i Credit(child_i) + γ_gap`。**完成只由 `Post` 证书结算**；信用永远只是排序信号，不构成任何授权。

**P30 步骤分引导的单调搜索律（Step-Credit Guided Monotone Search）**
SCGS 仅做重排与剪枝，不新增授权：`F_v17 = {plan ∈ F_v16 : 每个 Action 的 GVC = SUPPORTED}`。搜索对信用单调（信用提高不会使已选计划变差）；接地冲突即中止该分支；任何信用提升不得越过 `Post` 证书门槛；重排必须带滞回（hysteresis），防止信用抖动导致决策抖动。

## 3. 与基线的接口（如何退化）

- GCE 失效 ⇒ 接地中立元：`GVC ≡ SUPPORTED` 全集，`Pre_v17 = Pre_v16`，**等价 v16**；
- SCC 失效 ⇒ 信用中立元：`σ ≡ v16 的 val(n)`，瓶颈代数退化为 v16 的价值比较，**等价 v16**；
- SCGS 失效 ⇒ 静态 CSC 顺序，无 beam、无剪枝，**等价 v16**；
- 三者全失效 ⇒ MetricVoiceGauge-NCD-HUTDH-v16，再沿 v16→v15→v14→v13→v12→v11→v10→v9→v8→v7→v6 退化链退回；
- **安全继承**：GCE 只收紧前置，SCC 只提供价值不提供授权，SCGS 只重排/剪枝；三端口互不相交，均不能新增授权或放宽任何阈值；`Exec_v17 ⊆ Exec_v16` 由引理 137 与引理 141 保证。

## 4. 预期贡献

1. **接地证书化 VQA**：把视觉问答从"答案准确率"改写为"证据接地证书"，给出视角鲁棒性、组合式提问、拒答路由的形式语义，填补"感知模型输出直接进安全回路"的空白；
2. **瓶颈信用证书**：把过程奖励从可求和标量改写为不可洗白的共形下界，给出合取/析取/阈值并行的信用代数与保守性证明，解决"稠密奖励在长程具身任务中不可证"的问题；
3. **接地步骤证书搜索**：把 beam search 的启发式替换为已校准信用，同时用接地证书做纯剪枝，证明其不扩张授权且弱支配 v16 的任意打破平局；
4. **信用—授权分离**：明确"信用只排序、Post 才结算、里程碑只认 Post"的三权分立，使反洗白从启发式检测升级为结构性质；
5. **感知—进度—搜索—执行四层分离**：v12 管"允许什么"，v13 管"时限内实现多少"，v15 管"技能如何扩散"，v16 管"全身行为如何执行"，v17 管"机器人能证到什么、进度多少"，用 `Exec_v17⊆Exec_v16⊆Exec_v15⊆…` 解耦；E691–E710 覆盖接地共形性、信用反洗白、搜索不扩张、视角鲁棒、端到端与消融。

## 5. 本轮最大风险

**一句话**：步骤分本质由 PRM/标注者给出，而 PRM 可被优化目标逆向利用（Goodhart），一旦任何一层把累计信用——而非 `Post` 证书——接成里程碑或阶段解锁条件，可求和的信用就会变成洗白通道，使系统在"每步都有分、整条链却从未合取成立"的情况下执行一个**被稠密分数认证、却被证书否决的**动作。

```python
# IP-416/417/418/428 Grounding Certificate Engine：VQA 接地证书
class GroundingCertificateEngine:
    def __init__(self, vqg, cgc, cgd, eta=0.8):
        self.vqg = vqg            # IP-417：区域对齐 + 蕴涵统计
        self.cgc = cgc            # IP-418：共形阈值与视角鲁棒性校准
        self.cgd = cgd            # IP-428：组合式问题分解/合成
        self.eta = eta

    def answer(self, I, q, alpha_g):
        """返回 (answer, GVC, mode)；mode ∈ {GROUNDED, ABSTAIN, CONTRADICT}"""
        subs = self.cgd.decompose(q)                 # 单跳问题退化为 [q]
        certs = []
        for sub_q in subs:
            R, V = self.vqg.ground(I, sub_q)         # 区域 + 证据视图
            if not R:
                certs.append(GVC.empty('UND'))
                continue
            tau = self.vqg.entail_stat(I, sub_q, R, V)
            L_g = self.cgc.lower_bound(tau, alpha_g)  # 共形下界
            stable = self.cgc.view_stable(R, V)       # 视角扰动一致性
            if L_g >= self.eta and stable:
                g = 'SUPPORTED'
            elif self.cgc.contradicted(tau):
                g = 'CONTRADICTED'
            else:
                g = 'UNDETERMINED'                    # 拒答是一等公民
            certs.append(GVC(R, V, tau, L_g, alpha_g, self.eta, g))
        return self.cgd.compose(q, certs), certs


# IP-419/420 Step-Credit Certificate：把 PRM 分数校准为共形下界
class StepCreditCertificate:
    def __init__(self, prc):
        self.prc = prc            # IP-420：过程奖励校准器

    def score(self, step, x, post_cert):
        raw = self.prc.predict(step, x)              # PRM 原始步骤分
        low, up = self.prc.calibrate(raw)            # 共形区间
        low = 0.0 if post_cert is None else max(0.0, low)
        return SCC(step=step, sigma_low=low,
                   sigma_up=min(1.0, up),
                   credit_map=self.prc.credit_map(step),
                   post_cert=post_cert)


# IP-421 Credit Algebra Composer：瓶颈代数（禁止跨合取求和）
class CreditAlgebraComposer:
    def compose(self, kind, children, k=None):
        los = [c.sigma_low for c in children]
        ups = [c.sigma_up for c in children]
        if kind == 'Sequence':
            # 短板决定进度；禁止 sum，否则就是洗白通道
            return min(los), min(ups)
        if kind == 'Selector':
            return max(los), max(ups)
        if kind == 'Parallel':
            srt = sorted(los, reverse=True)
            return srt[k - 1], sorted(ups, reverse=True)[k - 1]
        if kind == 'Decorator':
            return min(los), min(ups)                # 只收缩
        raise ValueError(kind)

    def settle(self, node, post_cert):
        """结算：只认 Post 证书，信用再高也不能替代"""
        return post_cert.holds()


# IP-424 Credit Laundering Detector：结构性反洗白
class CreditLaunderingDetector:
    def __init__(self, gamma_gap=0.02):
        self.gamma_gap = gamma_gap

    def check(self, path, aggregate, post_holds):
        # 1) 禁止在合取路径上求和
        if self._used_sum_on_conjunction(path):
            return True
        # 2) 信用与 Post 背离：信用高但未证完成
        if aggregate >= 1.0 - self.gamma_gap and not post_holds:
            return True
        # 3) 账本守恒：聚合信用不得超过可证上界 + 间隙
        if aggregate > self._max_certified(path) + self.gamma_gap:
            return True
        return False


# IP-422 Step-Credit Guided Search：只重排 + 剪枝
class StepCreditGuidedSearch:
    def __init__(self, bts, gce, cac, cld, W=4, theta=0.0):
        self.bts, self.gce = bts, gce
        self.cac, self.cld = cac, cld
        self.W, self.theta = W, theta

    def search(self, x, m_star, h_star, budget):
        # 起点：v16 的可行树根；SCGS 不新增任何节点
        beam = [self.bts.root]
        for _ in range(budget):
            cand = []
            for node in beam:
                for child in self.bts.children(node):
                    gvc = self.gce.ground_child(child, x)
                    if gvc.status != 'SUPPORTED':
                        continue                       # 纯剪枝
                    sigma_low, _ = self.cac.compose(
                        child.kind, child.children)
                    if self.cld.check(child.path, sigma_low,
                                      child.post_cert.holds()):
                        continue                       # 洗白路径剪除
                    cand.append((sigma_low, child))
            # 只按信用重排，集合仍是 F_v16（不扩张授权）
            cand.sort(key=lambda t: t[0], reverse=True)
            beam = [n for _, n in cand[:self.W]]
            if not beam:
                break
        return self._settle_by_post(beam)              # 只由 Post 结算

    def _settle_by_post(self, beam):
        for node in beam:
            if node.post_cert.holds():                 # 唯一结算条件
                return node
        return None                                    # 无完成 -> 继续/回退
```

## 2. 推导

**引理 137（接地前置的可行域收缩）** 设每个 Action 节点的前置被替换为 `Pre_v17 = Pre_v16 ∩ {x : GVC = SUPPORTED}`，且 `UNDETERMINED`/`CONTRADICTED` 一律走 `Fallback`。则 v17 的可达动作集是 v16 的子集：`Exec_v17^{GCE} ⊆ Exec_v16`。证明：`Pre_v17 ⊆ Pre_v16`，tick 语义与 v16 引理 131 不变，故凡 v17 可执行的动作其 `Pre_v16` 必成立；`Fallback` 由 v16 保证落在 `Pre_v16` 内。∎ 推论：**感知接地只能收缩可行域，不可能新增授权**；VQA 的错误只可能让系统更保守，不可能更激进。

**引理 138（瓶颈信用的反洗分性）** 设 Sequence 的子步骤信用为 `σ_i`，认证间隙为 `γ`。若复合信用定义为 `Credit = min_i σ_i`，则任一尚未由 `Post` 结算的执行满足 `Credit ≤ 真实完成度 + γ`；且任何聚合 `A` 若在某个子步骤为 0、其余为 1 的赋值下仍给出 `A ≥ (n-1) − γ`，则 `A` 不保守（该赋值真实完成度为 0）。证明：`min` 由瓶颈子步骤决定，真实完成度不可能超过瓶颈 + 间隙；构造赋值 `σ_1=0, σ_{2..n}=1`，求和型 `A = n−1`，而真实进度为 0，故违反保守性。∎ 推论：**跨合取求和正是信用洗白通道**；`min` 是保守聚合的上确界，`max`/`order-stat` 只在析取/阈值并行处合法。

**引理 139（信用的可银行不可结算性）** 设信用下界沿安全执行为单调不减，且每次入账必须携带该步 `Post` 成立性或 `γ_gap` 认证。则银行信用 `β_t` 满足 `β_t ≤ 1`，且对任意 t，`β_t` 的增量只来自已认证的前缀；`β_t` 不可用于跨节点授权。证明：对执行步归纳。入账规则只接受 `Post` 成立或瓶颈下界，故 `β_t` 不可能超过已证进度；单调性由 `Post` 成立的持久性保证。跨节点使用时缺少 `Post` 引用，被 `settle` 拒绝。∎ 推论：**信用可以"存起来改进排序"，但永远不能"花出去换取授权"**。

**引理 140（接地证书的视角共形有效性）** 若对每个问题，校准视图与测试视图可交换，则误支持率满足 `P(g=SUPPORTED ∧ ¬entail) ≤ α_g + ρ_shift`。对 d 个组合子问题，若各子证书独立校准，总体误支持率 ≤ `Σ_i α_{g,i} + d·ρ_shift`；若交换性被破坏，界退化为 `α_g + ρ_shift` 且可能为空界。证明：单跳由共形覆盖定理直接给出，漂移项由 Le Cam 不等式（TV 距离）加到误覆盖率上；多跳由并集界合成。∎ 推论：**组合式提问必须逐子问题校准**，用单一整体阈值会系统性低估风险。

**引理 141（SCGS 不扩张授权与弱支配）** SCGS 的候选集合 `F_v17 = {plan ∈ F_v16 : 每个 Action 的 GVC = SUPPORTED ∧ ¬CLD}`，搜索只在 `F_v17` 内按信用降序选择，且结算必须 `Post` 成立。因此 (1) `Exec_v17 ⊆ Exec_v16`；(2) 若信用下界已校准且单调，SCGS 返回计划的信用不低于 v16 任意打破平局策略的期望信用。证明：(1) 由构造，剪枝只删、重排不增；结算引用 `Post`，与 v16 一致。(2) 在同一可行集上按更高下界排序，所选元素的下界不小于任意固定顺序所选元素的下界。∎ 推论：**步骤分只能让系统在同样安全的集合里更聪明，不能让它更冒险**。

**引理 142（信用洗白的不可完全检测性与保守代数的充分性）** 判定"聚合信用是否对应真实进度"至少和判定 `Post` 一样难；对任何不以上界为瓶颈的聚合 `A`，存在零进度路径使 `A → ∞`。因此完全防止洗白不能依赖检测器；充分条件是 (a) 瓶颈代数、(b) `Post` 结算、(c) 信用不接入任何授权。证明：取 n 个步骤各有 `σ = 1−ε` 但 `Post` 全不成立，则 `A_sum = n(1−ε) → ∞` 而真实进度为 0；`min` 给出 `1−ε`，但结算被 `Post` 拒绝。故安全来自结构 `(a)+(b)+(c)`，而非 CLD 的检测完备性。∎ 推论：**CLD 是告警器不是安全保证**；安全性的真正锚点是"信用永不授权 + Post 才结算"。

## 6. 已知风险与失效模式

1. **接地证书的区域不稳定**：同一答案可能有多个合理区域，`R` 随视角漂移，导致 SUPPORTED 反复翻转。缓解：区域投票、多假设 `Selector`、视角一致性余量、置信集而非单点。
2. **组合式提问的交换性破坏**：多跳分解后子问题不再可交换校准，共形界失效。缓解：逐子问题独立校准、Bonferroni/EVT、组合前做交换性检验。
3. **PRM 的系统性高估（Goodhart）**：`σ_low` 在训练分布内校准，在分布外系统性高估。缓解：OOD 检测、保守分位、对抗校准、信用上界截断。
4. **瓶颈代数的过度悲观**：长 Sequence 的 `min` 信用迅速趋零，搜索退化为贪心。缓解：分层瓶颈、局部信用归一化、允许有界次优、按子目标分段。
5. **信用洗白检测的假阴性**：CLD 无法完备检测，只能告警。缓解：把安全性建立在"信用不授权 + Post 结算"结构上，CLD 仅作监控（引理 142）。
6. **接地门与决策时延的冲突**：GCE 每帧数毫秒，叠加 v16 后可能超出 50Hz 预算。缓解：异步接地、缓存热点问题、视觉 token 复用、分级频率。
7. **拒答过多导致活性下降**：保守 γ/η 会让系统频繁 ABSTAIN，任务无法推进。缓解：主动询问、主动探测视角、拒答预算、按任务价值调整 η。
8. **可信度与真实进度的错位**：信用高但 `Post` 迟迟不成立，造成"永远 RUNNING"。缓解：设置 RUNNING 步数上限、强制回退、进度停滞检测。
9. **证据账本的隐私与存储**：逐帧记录区域/视图成本高且可能含敏感信息。缓解：环形缓冲、摘要哈希、按需落盘、脱敏。
10. **多答案择一的合取错误**：Selector 分支各自接地，但父节点误用析取当作合取。缓解：类型化证书代数、编译期检查、形式化单测。
11. **里程碑解锁被信用污染**：实现中若误把 `Credit≥θ` 接到 `MCB`，反洗白论证整体崩塌。缓解：`MCB` 只接受 `Post` 引用、代码级禁止信用入参、审计测试（E708）。
12. **累计保守性衰减**：v17 叠加 v16–v6 证书后下界逼近零，只剩 Fallback。缓解：选择性放宽（须形式化证明）、信用只排序不叠加授权、元监控余量。

## 7. 本轮最大风险

**一句话**：v17 的全部安全性都押在"信用只排序、`Post` 才结算、里程碑只认 `Post`"这条三权分立上；只要实现层留下一条把累计信用（哪怕是瓶颈 `min`）接通里程碑或阶段解锁的通路，Goodhart 化的 PRM 就能让系统在"每步都有分、整条链从未合取成立"的情况下推进——即**接地看着成立、信用看着很高、授权链却已被分数污染的**、最隐蔽的洗白式失效。
