# 想法区 · 第 3 轮：一条区间不等式，和它该站的位置

**灵感词**：最短路算法 / 深度学习 / 算法范式
**起点**：v1.2「X-DUB/PO*」。它把 DEC 的状态压成 `(est,A)` 的 Pareto 前沿，在 12 个 m=3 硬实例上做到 15.2× 节点、10.5× 时间。本轮先把同一套生成器扩到 38 例（n=12–21），v1.2 需要 **433,427 节点 / 7.3 s**；然后问一个更基本的问题：这些节点里，有多少是在证明一条本来可以一行写完的不等式？

## 一、先审计：94.8% 的搜索在重证一条算术

我在 38 个实例的 `h=OPT−1` 上，先不算搜索，只算一个东西：对每个区间 `[a,b]`，剩余任务**必须**落在区间里的加工量 `W(a,b)`，与机器在区间里的**可用容量** `cap(a,b)`。如果 `W>cap`，这个状态直接不可行，证书就是一条区间 `(a,b)` 加一个强制向量。

结果分成三类：

```text
32/38  根部的区间下界恰好等于 OPT（gap=0）
 3/38  gap=1（h*=OPT−1）
 3/38  gap=2（h*=OPT−2）
```

更刺眼的是节点账：**14 个实例在根部被一条区间不等式直接闭合**，这 14 个实例在 v1.2 里花掉了 **410,698 个节点**，占 38 例总节点的 **94.8%**。另外 18 例在 v1.2 的 DEAD/PACK 层就已 1 节点闭合；真正发生搜索的只有 20 例，其中 14 例可以被一条区间证书替代。也就是说，v1.2 的绝大部分搜索，不是在探索组合结构，而是在用分支定界重新证明一条计数不等式。

十四个见证（`a,b,W,cap`，超出量只有 1–3）：

```text
hard3#0   n=13  [ 4,27] W= 70  cap= 69   +1
hard3#1   n=12  [17,19] W=  7  cap=  6   +1
hard3#4   n=16  [ 4,37] W=101  cap= 99   +2
hard3#6   n=12  [22,25] W= 10  cap=  9   +1
hard3#7   n=16  [15,17] W=  7  cap=  6   +1
hard3#8   n=14  [ 3,30] W= 83  cap= 81   +2
hard3#9   n=12  [17,23] W= 19  cap= 18   +1
hard3#11  n=15  [ 9,34] W= 76  cap= 75   +1
large_b#3 n=18  [ 9,33] W= 74  cap= 72   +2
large_b#8 n=20  [ 9,44] W=106  cap=105   +1
large_a#0 n=18  [18,45] W= 84  cap= 81   +3
large_a#7 n=18  [ 6,41] W=106  cap=105   +1
large_het#0 n=18 [ 4,36] W= 97  cap= 96   +1
large_het#7 n=19 [ 4,40] W=109  cap=108   +1
```

这不是「又一个启发式」。它是**单调性 + 计数**：把区间外能放的工作全部减掉，剩下的必须挤进区间；区间里的机器时间是有上限的。v1.2 的容量层已经会算「总容量对不对」，但它把时间窗口丢了；DEC 层又只在窗口上做逐任务的 `est+p+q≤h`，从没把「同一时间窗里所有任务一起挤」这件事算进去。

## 二、直觉：搜索在找路径，证书在找割

把 DEC 看成一张 DAG：状态是 `(R,A,est)`，一条边是「在某台机器上排一个就绪任务」，一条从根到 `R=∅` 的路径就是一个排程。最短路算法在这里给了两个不同的东西：

1. **下界可以先于搜索**。如果对每个状态都能算一个「完成时间的下界」`Φ(σ)`，那么 `Φ(σ)>h` 就是一个不用展开子树的割。区间不等式正是这样的 `Φ`：`W(a,b)` 个单位的工作必须在 `[a,b]` 里做，机器在区间里最多提供 `cap(a,b)` 个机器时间；装不下就无解。
2. **剪枝与排序是两件事**。一个**廉价的** admissible 下界（max 负载 / 尾部 / 平均负载）拿去做子节点排序，节点从 25,931 涨到 2,503,920（见第五节）；而完整的区间 `Φ` 排序在 3 个 YES 例上是 2 好 1 坏，但每次子节点要付 `O(k^3)`，且排序对 NO 证明的节点数没有任何影响。admissible 不等于 useful，更不等于「值得付这个代价」。

所以本轮的范式判断是：**把 DEC 从「找一条可行路径」改写成「找一张最短的反驳证书」**。搜索仍然完备，但它每到一个节点先问：这里有没有一条一行就能写完的「不可能」？

## 三、形式化：强制工作量与可用容量

固定状态 `σ=(R,A,est)` 与期限 `h`。对任务 `i∈R`，令

```text
r_i = est_i,     d_i = h − q_i(R),     p_i = 加工时间.
```

`d_i` 是 `i` 的最晚完成时间（`q_i` 是 `i` 到汇点的最长路，不含 `p_i`）。对区间 `[a,b]`，定义 `i` 在区间内的**强制工作量**

```text
α_i(a,b) = max(0, min(p_i, b−a, r_i+p_i−a, b−d_i+p_i)).
```

这是「无论怎么排，`i` 至少有这么多加工必须发生在 `[a,b]` 里」。机器 `k` 在 `[a,b]` 里从 `max(a,A_k)` 才开始可用，所以总可用容量是

```text
cap(a,b) = Σ_k max(0, b − max(a,A_k)).
```

**区间规则（INT）**：

```text
若  Σ_i α_i(a,b) > cap(a,b)，则 FEAS(σ,h)=NO，
证书为 (a,b,α,cap)。
```

根部 `A=0` 时 `cap=m(b−a)`，这就是经典的区间能量推理；`A>0` 时容量随机器占用而缩小，规则变成**状态相关**的。这一点是本轮真正的位置判断：**同一个不等式，在根部是全局反驳，在深处是局部剪枝**。

## 四、位置经济学：根上一刀，深处一刀

我先只把 INT 放在根部（每个实例算一次），再逐步下放。38 例上的节点/时间：

| 配置 | 节点 | 时间 | 建表 |
|---|---:|---:|---:|
| v1.2 `sub`（基线） | 433,427 | 7.28 s | 61,169 |
| 根部 INT（全局容量） | 22,743 | 0.37 s | 4,891 |
| 全深度 INT（全局容量） | 21,946 | 0.88 s | 4,797 |
| 全深度 INT（逐机器容量） | 6,258 | 0.37 s | 1,133 |
| 全深度 + `est` 规范化 | **5,318** | **0.32 s** | **849** |

根上一刀砍掉 95% 的节点，是因为 14 个实例的整棵搜索树被一条证书替代；但根部之后，全局容量在深处不再变强：全深度只再省 3.5% 节点，时间反而从 0.37 s 涨到 0.88 s（+136%）。**把容量换成逐机器的 `cap(a,b)` 之后，深处的调用突然值钱了**：同样全深度，节点从 21,946 降到 6,258（−71%），时间从 0.88 s 降到 0.37 s（−58%）；剩余任务 `k` 小，单次检查只要几十微秒，而 `A_k>0` 让容量真正变窄。最后一步的 `est` 规范化再省 15% 节点（5,318）、12% 时间（0.32 s）。

这也解释了为什么「根部一刀」不是终点：**证书的成本随深度下降，收益却不随深度下降**。根部的 `k=n`，单次 0.65 ms（n=20）；深处的 `k=6`，单次几十微秒。同一个不等式在深处是廉价的。

## 五、最短路给的第二个教训：剪枝与排序是两件事

既然 `Φ` 是完成时间的下界，最自然的 A* 做法是「按子节点的下界排序」。我先试了**廉价版**（只用 max 负载、尾部、平均负载，不跑区间扫描），在 `h=OPT` 找第一个 YES，结果是一场灾难：

| 排序 | 节点 | 时间 |
|---|---:|---:|
| v1.2 slack 序 | 25,931 | 0.44 s |
| 廉价下界序（max 负载/尾部/平均负载） | 2,503,920 | 49.4 s（1 例触 2M 上限） |

原因不神秘：廉价下界只看「负载/尾部」，不看「这个子状态是否还能装下」。一个负载很均衡、下界很漂亮的子状态，可能下一层就被容量表判死；按它排序会一路钻进去。**admissible 的下界负责说「这里不可能」，不负责说「那里最可能」**。

我又试了完整的区间 `Φ` 排序（每个子节点都跑一次 INT）：在 hard3#8 上 1,377→238，hard3#9 上 1,332→671，但 hard3#0 上 15→22，时间分别为 0.035 s / 0.057 s / 0.009 s，并不稳定。更关键的是：**排序对 NO 证明的节点数没有影响**——本轮 38 例的 KPI 是 `h=OPT−1` 的 NO 证明，排序帮不上忙，只会把每个子节点的代价乘以 `O(k^3)`。所以本轮不做排序，子节点顺序仍然是 v1.2 的 slack 序。

## 六、深度学习：只配做调度器，而调度器的天花板是 24%

深度学习的自然位置是「学习何时调用证书」：每个节点都跑 INT 太贵，能不能学一个 dispatcher，只在会命中的节点调用？

我先不训练，先算**神谕上限**。全深度 INT 共 2,079 次调用、1,213 次命中、INT 时间 0.185 s，总时间 0.32 s。一个知道每一次调用会不会命中的神谕 dispatcher，只需要付 1,213 次命中的钱：

```text
T_oracle = (0.32 − 0.185) + 1,213 × (0.185/2,079)
         = 0.135 + 0.108 = 0.243 s
```

也就是**最多省 24%**，节点数一根不差（跳过只会少剪枝，不会多剪枝）。任何 false negative 都会把节点加回来。为了这 24%，要一个节点级分类器、特征抽取、阈值校准和一次训练；而同样的工程量拿去做「把容量从全局换成逐机器」，节点从 22,743 降到 6,258（再规范化到 5,318）、时间还降了。

所以我本轮对深度学习的结论是**否定式的**：在证书优先的搜索里，学习应该去学「证书的值不值得算」，但本轮的证书太便宜，学它的调度器没有足够的天花板。真正有效的动作是**把证书做得更便宜、更状态相关**，而不是学习何时调用它。作为工程折中，我只留了一个一位的在线门：根部最小间隔松弛 `>1` 时不再下放 INT。38 例上节点一根不差，60 个易实例上的额外开销从 +111% 降到 +52%。

## 七、结果

- 38 例（n=12–21）：v1.2 `sub` **433,427 节点 / 7.28 s / 61,169 表** → PACE **5,318 节点 / 0.32 s / 849 表**。节点 **81.5×**，时间 **22.8×**，建表 **72×**。
- 14 例被根部一条区间证书闭合；这 14 例在 v1.2 里是 410,698 节点。单张证书 16–24 个字段，检查器 6.2 µs（n=13）。
- 32/38 的区间下界等于 OPT；6 个残差实例的 gap 只有 1–2，PACE 在它们身上仍比 v1.2 少 4.3× 节点（22,711 → 5,286）。
- 12 个原 v1.2 硬实例：69,690 → 3,850 节点（18.1×），1.15 s → 0.23 s。
- 正确性：2,400 组与无剪枝暴力/`sub` 对拍 0 不一致；38/38 的 YES 排程独立复核；802 条 INT 见证独立重算 0 无效。

## 八、负结果（和正结果一样重要）

1. **廉价下界排序灾难**：≥2,503,920 节点，1 例触上限。完整 `Φ` 排序在 3 个 YES 例上 2 好 1 坏，但对 NO 证明无益且每子节点 `O(k^3)`；本轮不做排序。
2. **深度学习调度器天花板 24%**：神谕都只省 24%，学习没有足够空间；真正有效的是把证书做便宜。
3. **资格子集 / 非抢占 clique 规则零增益**：在 38 例上不多闭一个实例；子集版还把 INT 时间从 0.185 s 拉到 2.63 s。
4. **`est`-fiber 剪枝在 A-aware 容量下不可靠**：v1.2 的 `(est,A)` 支配要求两者都小；我一度想只用 `est` 做 cut，但逐机器容量依赖 `A`，这个方向不成立。限制到「区间起点 `a≥max A` 的 A-free 窗口」后是可靠的，但 38 例只命中 1 次。**A-aware 强化破坏了 A-independence，这是本轮最值得记住的取舍。**
5. **易实例开销**：60 个 `h=OPT+5` 的易实例，v1.2 0.062 s，PACE 0.131 s（+111%），加一位门后 0.094 s（+52%）。节点少了 65%，但时间更贵；这是 `O(k^3)` 检查的常数代价。

## 九、一句话最大风险

**81.5× 的节点收益里，14 个实例各由一条区间不等式独立闭合；剩下 6 个只降到 4.3×，而这类不等式对窗口宽松、纯组合装箱的实例可能完全不触发——那时 PACE 只是给 v1.2 加了 1.5–2× 的常数开销。**

# 产物区 · v1.3：X-DUB/PACE*

> PACE = Potential-Augmented Certificate Engine：在 v1.2 的 PO-DEC 上增加一个**区间容量证书层**（tier 1.25），把「搜索排程」改写成「搜索最短反驳」。
> 中文名：区间势能证书引擎
> 状态：设计稿 + 可运行实现与对拍；2,400 组无剪枝/跨实现一致性、38/38 YES 排程复核、802 条 INT 见证独立重算；38 个实例（n=12–21）主实验、14 条根部证书、深度/容量/规范化/门控消融、60 个易实例开销、廉价下界排序反例、调度器神谕上界、INT 规模基准。未接 PSPLIB，未做形式化验证，n≥22 未系统测试。

## 0. 版本关系与本轮增量

v1.2 的资产全部保留：`LC-PACK` 的 0/0.5/1/2/3 层、`LC-DEC`、`CHECK-LC`、`PROFILE` 的位并行与对偶池、`(est,A)` Pareto 前沿 `G`、孪生机器商 `CANON`、`FRONT`/`FRONT-SUB` 证书。

v1.3 只加一层、改一处顺序、加一个规范化：

1. **tier 1.25 `INT`（区间容量证书）**：在 DEC 的每个节点，枚举区间 `[a,b]`，计算剩余任务的强制工作量 `W(a,b)` 与机器在区间内的可用容量 `cap(a,b)`；若 `W>cap`，返回 `NO-INT(a,b,α,cap)`。合法性来自定理 1–3。
2. **`INT` 放在 `PACK` 之前**：`INT` 是整问题的松弛，失败必然意味着 `PACK` 也失败；先跑 `INT` 可以跳过数百次建表（全深度配置下 1,133→849）。
3. **`est` 规范化**：对 `est_i < min_{k∈E_i} A_k` 的任务，把 `est_i` 抬到 `min_{k∈E_i} A_k`。这是等价状态（定理 5），但它让 `(est,A)` 前沿少掉大量伪不可比，节点再降 15%。
4. **一位门控 `g1`（可选）**：根部最小间隔松弛 `>1` 时不再下放 `INT`。38 例节点不变，60 个易实例的额外时间从 +111% 降到 +52%。

退化关系：

```text
关 INT、关规范化，只留 PACK        → 逐字回到 v1.2 的 sub
开 INT 但只跑根部        → "root" 对照
INT 用全局容量 cap=m(b−a)              → "global" 对照
INT 用逐机器容量 cap=Σ(b−max(a,A_k))_+  → 本轮的 PACE
```

## 2. 形式定义

**定义 1（状态图与可行性）**。状态图 `G_h` 的顶点是 `(R,A,est)`；对每个就绪任务 `i`（`R` 中无前驱）与每台 `k∈E_i`，若 `t=max(A_k,est_i)` 且 `t+p_i+q_i(R)≤h`，有一条边到

```text
(R\{i}, A[k←t+p_i], est' ),   est'_j = max(est_j, t+p_i)  (j∈succ(i)).
```

`FEAS(σ,h)` 为真当且仅当存在从 `σ` 到 `R=∅` 的路径（路线上每个 `t` 都满足期限；`A` 的终值给出排程）。

**定义 2（强制工作量）**。对 `i∈R`、区间 `[a,b]`：

```text
α_i(a,b) = max(0, min(p_i, b−a, r_i+p_i−a, b−d_i+p_i)).
```

**定义 3（区间容量）**。

```text
cap(a,b) = Σ_{k=1..m} max(0, b − max(a, A_k)).
```

**定义 4（INT 规则与证书）**。若 `W(a,b)>cap(a,b)`，返回 `NO`，证书

```text
NO-INT(a, b, α[1..k], cap)
```

其中 `α` 与 `cap` 可由 `(R,A,est,h)` 重算。检查器只需 `O(k+m)`。

**定义 5（规范化）**。`NORM(σ)`：对每个 `i∈R`，若 `est_i < min_{k∈E_i} A_k`，令 `est_i ← min_{k∈E_i} A_k`；否则不变。

**定义 6（PACE-DEC）**。

```text
PACE-DEC(σ,h):
  1  if R=∅: return YES([])
  2  if DEAD(σ): return NO(DEAD)
  3  σ ← NORM(σ);  A* ← CANON_R(A);  estt ← (est_i)_{i∈R}
  4  if exact-memo[(R,A,est)]: return NO
  5  if ∃(est',A')∈G_{R,h}: est'≤estt ∧ A'≤A*:
         return NO(FRONT-SUB)
  6  if INT(σ,h) returns (a,b,α,cap):
         return NO(NO-INT(a,b,α,cap))
  7  if ∃A'∈F_{R,h}: A'≤A*: return NO(FRONT)
  8  ok ← PO-LC-PACK(σ,h)                 # v1.2 的 0/0.5/1/2/3 层
  9  if ¬ok: exact-memo←h; F_INSERT; return NO(PACK)
 10  for child in CHILDREN(σ) sorted by slack:
 11      r ← PACE-DEC(child,h)
 12      if r=YES: return YES([(i,k,t)]+r)
 13  G_INSERT(R,h,(estt,A*)); exact-memo←h
 14  return NO(RESOLVE)
```

**定义 7（INT 子程序）**。

```text
INT(σ,h):
  1  k ← |R|;  if k=0: return ⊥
  2  r_i ← est_i;  d_i ← h−q_i(R);  p_i ← p_i
  3  S ← {r_i} ∪ {d_i−p_i};   T ← {d_i} ∪ {r_i+p_i}
  4  for a∈S, b∈T with b>a:
  5      cap ← Σ_k max(0, b−max(a,A_k))
  6      W ← 0;  α ← [0]*k
  7      for i∈R:
  8          v ← min(p_i, b−a, r_i+p_i−a, b−d_i+p_i)
  9          if v>0: α[i] ← v; W ← W+v
 10      if W>cap: return (a,b,α,cap)
 11  return ⊥
```

**定义 8（证书语言，增补）**。

```text
CERT ::= ...                                   # v1.2 全部节点
       | NO-INT(a,b,α,cap)                     # 本轮：区间容量叶子
       | NO-RESOLVE(children)                  # 子节点全 NO
```

检查器：对 `NO-INT` 重算 `r,d,α,cap`，验证 `α` 逐项相等、`Σα>cap`、`cap=Σ_k(b−max(a,A_k))_+`；对 `NO-RESOLVE` 递归检查子节点；对 `FRONT`/`FRONT-SUB` 按 v1.2 的向量不等式重放。

## 3. 定理与证明

### 定理 1（强制工作量是下界）

任取 `i∈R` 与 `[a,b]`。任何可行排程中，`i` 在 `[a,b]` 内的加工量至少为 `α_i(a,b)`。

**证明**。`i` 的执行区间是 `[s,s+p_i]`，`s∈[r_i, d_i−p_i]`。它与 `[a,b]` 的重叠

```text
g(s) = max(0, min(s+p_i,b) − max(s,a))
```

是 `s` 的梯形函数（斜率 +1、0、−1），故在区间端点取最小。代入 `s=r_i` 与 `s=d_i−p_i`，两点最小值经分段化简即

```text
max(0, min(p_i, b−a, r_i+p_i−a, b−d_i+p_i)).
```

∎

**注**：这是经典的区间能量/强制工作量（energetic reasoning）；本轮不声称不等式本身是新发现，新的部分是把它作为 DEC 状态上的证书层，并使用**状态相关的 `A`**。

### 定理 2（区间容量是上界）

任何可行排程在 `[a,b]` 内使用的机器时间不超过 `cap(a,b)`。

**证明**。机器 `k` 在 `A_k` 之前不可用，故它在 `[a,b]` 内的可用长度是 `max(0,b−max(a,A_k))`；每台机器同时最多做一个任务；资格限制只会减少可用性。求和得 `cap`。∎

### 定理 3（INT 规则可靠）

若存在 `[a,b]` 使 `W(a,b)>cap(a,b)`，则 `FEAS(σ,h)=NO`。

**证明**。反设存在可行排程。由定理 1，每个 `i` 在 `[a,b]` 内至少加工 `α_i`，合计至少 `W`；由定理 2，这些加工占用不超过 `cap` 的机器时间。`W>cap` 矛盾。∎

### 定理 4（PACE 可靠且完备）

`PACE-DEC(σ,h)` 返回 YES 当且仅当 `FEAS(σ,h)`，且返回的排程满足资格、优先与期限。

**证明**。对 `|R|` 归纳。`R=∅` 显然。`DEAD`、精确 memo、`FRONT`/`FRONT-SUB` 都是 v1.2 已验证的可靠剪枝。`INT` 失败由定理 3 得 NO；`INT` 通过则进入 v1.2 的 `PO-LC-PACK` 与子节点枚举，由归纳假设与 v1.2 的可靠性得等价。`NORM` 由定理 5 保持 `FEAS`。完备性：所有剪枝都是必要条件的否定（只排除不可行状态），未剪枝的分支被穷举。∎

### 定理 5（规范化是等价变换）

设 `σ'=NORM(σ)`。则 `FEAS(σ',h)=FEAS(σ,h)`。

**证明**。只需考虑被抬高的 `i`：`est_i<min_{k∈E_i}A_k`。任何可行排程把 `i` 放在某台 `k∈E_i` 上，开始时刻 `t_i≥A_k≥min_{k'}A_{k'}>est_i`，故原约束 `t_i≥est_i` 是冗余的；把下界抬到 `min A` 不改变可行域。逐任务应用。∎

### 定理 6（证书检查器可靠且完备）

`CHECK-INT` 接受 `(a,b,α,cap)` 仅当它确实是该状态的一条 INT 证书；`PACE` 发出的每条 `NO-INT` 都能被接受。

**证明**。检查器从 `(R,A,est,h)` 重算 `r_i,d_i`，逐项比较 `α`，重算 `cap`，再验证 `Σα>cap`。接受即满足定理 3 的前提。发出时 `α,cap` 正是 `INT` 计算的值，故必被接受。∎

### 定理 7（证明长度：从 410,698 个节点到 14 张叶子证书）

对一个被根部 INT 闭合的实例，PACE 的证明是单个 `NO-INT` 叶子，含 `2` 个端点、`k` 个强制量、`1` 个容量界，共 `k+3` 个整数（外加规则标签）；检查时间 `O(k+m)`。

**实测**：14 个这样的实例，v1.2 的证明合计 **410,698** 个节点（中位 9,925，最大 179,617）；PACE 的证书是 **14** 张叶子，字段数 16–24（中位 20），检查器 **6.2 µs**（n=13）。这不是分离定理，是一次**证明复杂度的经验坍缩**：同一批实例，搜索证明是千级节点，区间证明是十几个整数。

### 定理 8（标量下界 admissible，但不用于排序）

定义

```text
Φ(σ) = max( max_i (r_i+p_i+q_i),
            max_{a,b} ( a + ceil( W(a,b)·(b−a) / cap(a,b) ) ) ).
```

（约定 `cap(a,b)>0`，否则 INT 已在同一区间触发。）则 `Φ(σ)` 不超过从 `σ` 出发的任何完整排程的完成时间。

**证明**。第一项：`i` 最早 `r_i` 开工，做 `p_i`，再加尾部 `q_i`。第二项：`W` 个单位的强制工作必须在 `[a,b]` 内做，区间内的最大平均速率是 `cap/(b−a)`，故至少还要 `W(b−a)/cap` 的时间，完成不早于 `a` 加它。取最大仍是下界。∎

**注意**：`Φ` 只用于解释与 `INT` 的动机；实现里不按 `Φ` 排序。原因见第 5.7 节：一个 admissible 的**廉价**下界做排序器会灾难性变差；完整 `Φ` 排序在 3 个 YES 例上 2 好 1 坏，但对 NO 证明无益且每子节点 `O(k^3)`。

### 定理 9（每节点无害，渐近类不变）

固定 `m`，PACE 在每个被访问节点最多增加 `O(k^3+k^2 m)` 的 `INT` 检查与 `O(km)` 的规范化；它不增加搜索分支，不改变 YES/NO。额外的总代价是

```text
O(Σ_{σ visited} (k_σ^3 + k_σ^2 m)).
```

最坏情形仍是搜索的指数复杂度；收益来自被 `INT` 提前剪掉的子树与跳过的建表，而不是渐近类的改变。

## 4. 复杂度

| 对象 | 时间 | 空间 |
|---|---|---|
| `INT`（单节点，`k` 个剩余任务） | `O(k^3 + k^2 m)`；`O(k^2)` 个区间 × `O(k+m)` | `O(k+m)` |
| 根部 `INT` | `O(n^3+n^2 m)`；实测 n=20 0.65 ms，n=160 27.4 ms | `O(n+m)` |
| `NORM` | `O(km)`（可增量优化） | `O(k)` |
| `CANON` | `O(km)` | `O(m)` |
| `PACK`（tier 3） | `O(n·m·|L|max)`，v1.2 原样 | `O(|L|max)` |
| `CHECK-INT` | `O(k+m)`；实测 6.2 µs（n=13） | `O(k)` |
| 整体 | `O(Σ k_σ^3 + T_PO-DEC)` | 同 v1.2 |

**成本随深度下降**：`k=|R|` 沿搜索递减，所以深处的 `INT` 单次只要几十微秒；这正是「根上一刀 + 深处全开」在时间上可行的原因。根部单次 0.65 ms（n=20）看起来贵，但一个实例只付一次。

### 5.7 排序反例（最短路的第二个教训）

在 `h=OPT` 上找第一个 YES，只改子节点顺序。这里用的是**廉价** admissible 下界（max 负载、尾部、平均负载；不跑区间扫描）：

| 集合 | slack 序（v1.2） | 廉价下界序 |
|---|---:|---:|
| `hard3` | 3,244 | 4,697 |
| `large_b` | 18,990 | **2,352,222**（1 例触 2M 上限） |
| `large_a` | 1,081 | 94,749 |
| `large_het` | 2,616 | 52,252 |
| **合计** | **25,931** | **≥2,503,920** |

廉价下界是 admissible 的，但排序仍然灾难：它偏爱「负载均衡、下界漂亮」的子状态，而这些状态常常下一层就被容量/期限判死。**admissible 负责否定，不负责推荐。**

完整的区间 `Φ` 排序则是混合的：hard3#8 1,377→238、hard3#9 1,332→671、hard3#0 15→22（时间 0.035/0.057/0.009 s）。但排序对 NO 证明的节点数没有影响；本轮 KPI 是 `h=OPT−1` 的 NO 证明，排序只会把每个子节点的代价乘以 `O(k^3)`。所以实现里保留 slack 序，把 `Φ` 严格限制为剪枝规则。

### 5.8 深度学习：调度器的神谕上界

全深度 INT：2,079 次调用，1,213 次命中，INT 时间 0.185 s，总时间 0.32 s。神谕 dispatcher 只付命中调用：

```text
T_oracle = (0.32 − 0.185) + 1,213 × (0.185 / 2,079)
         = 0.135 + 0.108 = 0.243 s
```

**上界：省 24%，节点数不变。** 任何 false negative 都会把节点加回来。为 24% 训练一个节点级分类器不划算；同样的工程量用于「全局容量→逐机器容量」，节点从 22,743 降到 6,258（再规范化到 5,318）。

**一位门控 `g1` 的工程折中**：根部最小间隔松弛 `>1` 时不再下放 INT。38 例节点仍 5,318（硬残差的根部松弛都是 0–1），60 个易实例从 0.131 s 降到 0.094 s。它只跳过检查，不影响正确性。

### 5.11 负结果

1. **资格子集容量零增益**：对每个 `S⊆[m]` 检查 `Σ_{E_i⊆S}α_i > Σ_{k∈S}(b−max(a,A_k))_+`，38 例节点一根不差，INT 时间从 0.185 s 涨到 2.63 s（14×）。异构资格下，瓶颈不是子集容量，而是任务窗口本身。
2. **非抢占 clique 规则零增益**：`2α_i>b−a` 的任务两两在 `[a,b]` 内重叠，超过 `m` 个即不可行；38 例上不多闭一个实例，只多花 20% INT 时间。
3. **`est`-fiber 剪枝不可靠**：v1.2 的 `(est,A)` 支配要求两者都小；我一度把 INT 失败只按 `est` 缓存，这在**全局容量**下是可靠的（容量 `m(b−a)` 与 `A` 无关），但换成逐机器容量后**不成立**：更早的 `A` 会给出更大容量，可能把失败态救活。限制到 `a≥max A` 的 A-free 窗口后可靠，但 38 例只命中 1 次。**A-aware 强化破坏了 A-independence，这是本轮最重要的取舍。**
4. **廉价下界排序**：≥2,503,920 节点，1 例触上限。完整 `Φ` 排序 3 例上 2 好 1 坏，但对 NO 证明无益且每子节点 `O(k^3)`；不做。
5. **调度器天花板 24%**：神谕都只省 24%，学习没有足够空间。
6. **易实例 +52%~+111%**：见 5.9。
7. **`g1` 门控不是定理**：它依赖「根部松弛小 ⇒ 深处会命中」的经验相关性；在别的分布上可能失效。它只影响性能，不影响正确性。

| 容量层 | tier 3 `PACK`（表/对偶） | 前面加 tier 1.25 `INT`（区间容量） |
| DEC 状态键 | `(R,A,est)` + `(est,A)` 前沿 | 同左，另加 `NORM` 规范化 |
| 新证书 | `FRONT`/`FRONT-SUB` | `NO-INT(a,b,α,cap)` |
| 建表时机 | 每个节点先 `PACK` | `INT` 先于 `PACK`，命中即跳表 |
| 子节点排序 | slack | slack（**明确拒绝**下界排序） |
| 学习 | 无 | 只有一位门控 `g1`；节点级 dispatcher 被神谕上界否掉 |
| 最大实例 | n=16（硬），n=22（随机） | n=21（硬），38 例系统测试 |
| 主结果 | 12 例 15.2× | 38 例 81.5× 节点 / 22.8× 时间 |

## 7. 已知风险

1. **收益高度集中**：14/38 个实例贡献了 94.8% 的节点削减，且每个只需一条区间证书。若真实工作负载的窗口更宽、或难度来自纯装箱/序列而非区间超载，`INT` 可能不触发；那时 PACE 退化为 v1.2 + 1.5–2× 常数开销（5.9 节实测）。
2. **基准偏差**：全部是随机生成器，n≤21，未接 PSPLIB/真实 RCPSP。`h=OPT−1` 的构造会放大「差 1 个单位」的区间超载；这是有意的压力测试，但不是无偏估计。
3. **`INT` 的最坏复杂度 `O(k^3)`**：根部 n=160 已 27 ms；n≥500 时根检查可能到秒级。逐机器版在深处便宜，但根部仍是三次方。
4. **`A`-aware 的代价**：逐机器容量比全局容量强，但破坏了 `est`-only cut；我们没能找到一个既 A-aware 又 A-independent 的投影。见 5.11(3)。
5. **规范化是逐节点 `O(km)`**：易实例上 0.094 s vs 0.062 s，一部分来自它；没有做增量实现。
6. **证书 DAG 可能很宽**：内部 INT 命中 1,213 次，完整证明要重放这些叶子 + `RESOLVE`；没有路径压缩。
7. **没有形式化验证**：定理 1–9 是纸面证明 + 2,400 组对拍 + 802 条见证重算；没有 Coq/Lean。
8. **时间常数是 Python 的**：`INT` 的 0.185 s 与建表的相对比例换 C 后会变；节点比与建表比是确定性的，时间比不是。
9. **`g1` 阈值是经验值**：`1` 是在本轮 38+60 例上选的，没有交叉验证；换分布需要重选。
10. **资格被 INT 忽略**：`cap` 假设所有机器都能做所有任务，这是合法的乐观松弛，但异构资格下会变弱；子集规则实测无增益，没有更好的办法。

---

## 8. 一句话最大风险

**81.5× 的节点收益里，14 个实例各由一条区间不等式独立闭合；剩下 6 个只降到 4.3×，而这类不等式对窗口宽松、纯组合装箱的实例可能完全不触发——那时 PACE 只是给 v1.2 加了 1.5–2× 的常数开销。**
