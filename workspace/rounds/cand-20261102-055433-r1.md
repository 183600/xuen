# 第 16 轮（研究线累计；新灵感循环第 1 轮）· CHORD-VLA：先解释残差，再决定信不信——用谐波减速器的物理零模型、流匹配的 ODE 证书和云端-边缘时延分解，把 ZEST 的「一个残差」拆成「三份账」

> 检索/复核日期：**2026-11-02（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮三个词是「谐波减速器」「流匹配策略」「云端协同」。**不推倒**第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO、第 13 轮 WAVE-SERVO、第 14 轮 VOI-MAP、第 15 轮 ZEST-VLA；CHORD 是 ZEST 残差层之内的一次**换对象**：从「残差是不是大」换成「残差里哪一份是我们能解释的」。

## 0. 先给直觉：ZEST 把「残差」当成一个数，但它其实是一个混合物

第 15 轮 ZEST 的核心动作很漂亮：把 VLA 的动作当预测、把执行后的观测当标签，用 `r_tmp, r_geo, r_goal, r_dyn` 四个自监督残差判断「这一步是否胜任」，再用 conformal + CUSUM 做一个风险受控的信任门。它的隐含假设是：

> **残差高 = 策略不胜任。**

但在 G1 + Dex1 上，这个假设不成立。残差至少有四个来源：

1. **策略真的不胜任**（OOD-E/OOD-S）：这是我们要抓的。
2. **谐波减速器的机构误差**：传动误差、滞回/失动、摩擦、扭转柔度。换向时尤其明显；它不是故障，是机构的确定性非线性。
3. **云端计划的时延/过期**：官方远程 VLA 返回 30 步计划时，机器人已经动了几步；计划本身对，只是「旧了」。
4. **感知噪声**：透明、反光、遮挡。

ZEST 把 1、2、3 混在一个标量里，于是会出现两种错误：

- **误报**：机器人在换向或云端延迟时残差升高，信任门误以为 VLA 不胜任，触发不必要的 fallback。
- **漏报**：如果机构/时延解释器把残差「解释掉」了，真正的策略失败也被一起减掉——这是本轮要正面处理的新风险。

所以本轮的直觉只有一句话：

> **不要对残差设阈值；先对残差做「解释」，再对解释不掉的部分设阈值。**

三个灵感词恰好给出三个解释器：

- **谐波减速器** → 一个低维、可标定、冻结的**物理零模型**，解释机构残差 `r_mech`。
- **云端协同** → 一个由时间戳和计划前缀驱动的**通信零模型**，解释时延残差 `r_stale`，并决定「重锚」还是「等新计划」。
- **流匹配策略** → 一张由 ODE 路径导出的**证书**：曲率、截断误差、多样本一致性。它既是云端-边缘之间压缩通信的对象，也是一个独立于几何残差的**语义不确定性审计信号**。

一句话先给押注：

> **第 15 轮用「动作-观测一致性」决定信不信 VLA；本轮先问「这个不一致能不能被机构或时延解释」：能解释就减掉，不能解释才进入信任门；再用流匹配 ODE 证书做独立审计，防止解释器把真失败一起吞掉。零样本泛化不只是「失败时退一步」，而是「退一步之前先知道自己在退哪一类失败」。**

三个可验证创新点：

1. **残差分解（residual decomposition）**：`r = r_pol + r_mech + r_stale + ε`；门控只阈值化 `r_pol`。机构模型是低维物理模型，时延模型是确定性前向仿真，二者都不是第二个学习策略。
2. **云端-边缘的流匹配证书（flow certificate）**：云端跑完整 ODE + 多样本，发送 `(x_0, plan, checkpoints, L, C, Δ_N, agreement, timestamp, state hash)`；边缘用曲率决定「线性重锚」还是「不重锚」，用一致性做独立审计。带宽可忽略，瓶颈是时延。
3. **解释器自审（explainer self-audit）**：当残差门「异常安静」但流证书持续异常时，说明解释器可能吞掉了失败；此时启用流通道交叉检查，或降低解释器增益。它把「过度白化」从不可见风险变成一个可观测的统计量。

## 1. 研究日志：为什么是这一层

### 1.1 第 15 轮留下的三个「未付费假设」

```text
A1. 残差是策略失败的充分统计量：残差高 ⇒ 策略错。
A2. 残差尺度在换向/接触/延迟下不变：一个 conformal 阈值够用。
A3. 解释残差不会伤害检测：减掉机构/时延项只会降误报。
```

A1 和 A2 是第 15 轮在合成实验里没有建模的；A3 是本轮要证伪的。真实 G1 的谐波减速器在换向时有明显的失动和滞回，Dex1 的手指关节也有传动间隙；这些都会让 `r_geo` 在「策略完全正确」时升高。官方远程 API 的延迟会让计划的前几步过期；这会让 `r_tmp` 在「策略完全正确」时升高。ZEST 的 conformal 阈值是在 ID 上校准的，如果校准集里换向/延迟样本少，阈值就会偏紧，评测时误报。

### 1.2 三个新判断

**判断 1：残差是一个混合物，应该换对象，而不是换阈值。**
不是再调一个 `q_α`，而是把 `r` 投影到「机构子空间」「时延子空间」「剩余子空间」。只有剩余子空间进入门控。这个换对象不引入新网络：机构模型是物理模型，时延模型是前向仿真，都是确定性的。

**判断 2：机构模型是「零模型」，不是「策略」。**
它的参数很少（每关节 3–8 个），只能解释一个低维子空间。策略失败如果有子空间外的分量，就仍然可见。这给出一个可证明的分离条件：失败残差与解释子空间的**主角**决定可检测性。主角接近 0 时，解释器可以把失败吞掉——这就是本轮最大的风险，必须写成命题，而不是藏起来。

**判断 3：流匹配的 ODE 路径是云端-边缘之间最好的「压缩表示」。**
云端不需要传图像或大特征，只需要传一条 ODE 路径的证书：初始噪声、若干检查点、路径长度、曲率、截断误差、多样本一致性、时间戳。边缘用这些做三件事：

- **时延重锚**：曲率小 ⇒ 计划局部近似直线，线性重锚误差有界；曲率大 ⇒ 不要重锚，交给信任门或请求新计划。
- **语义审计**：多样本不一致（低 agreement）是语义歧义/多模态的独立信号；几何残差可能完全正常。
- **过度白化审计**：如果残差门安静但流证书一直异常，说明「解释器可能把失败解释掉了」。

### 1.3 与第 15 轮的关系

| 层 | 第 15 轮 ZEST-VLA | 第 16 轮 CHORD-VLA |

**剪枝**：不训练第二个检测器；不做自监督预训练；不做 test-time weight update；不在本轮把流证书作为默认硬门控（合成实验显示它主场景不划算），只作为诊断/安全模式。

## 2. 机制草图（形式化见产物区）

### 2.1 谐波减速器不是噪声，是低维可解释项

对关节 `j`，设电机侧角 `q^m_j`、输出侧角 `q^o_j`、减速比 `N_j`。一个够用的集总模型是：

```text
q^o_j = q^m_j / N_j
        + δ^te_j(q^m_j)          # 周期传动误差
        + δ^hys_j(τ_j, m_j)      # 滞回/失动，m_j 是记忆状态
        + δ^fric_j(q̇^m_j, τ_j)   # 摩擦/粘滞
        + ε_j
```

- `δ^te` 用 1–3 次谐波：`Σ_l a_{j,l} sin(l q^m_j + φ_{j,l})`。
- `δ^hys` 用一个带记忆的死区：`m_j ← clip(m_j + η(sign(q̇^m_j) − m_j), −1, 1)`，`δ^hys = b_j m_j + c_j τ_j / K_j`。
- `δ^fric` 用 `f^c_j tanh(q̇^m_j / v_0) + f^v_j q̇^m_j`。

参数在一条慢速正弦 + 不同负载的标定轨迹上辨识，然后**冻结**。它不是第二个策略，是类似相机内参的标定。给定指令和测量，预测 `r_mech`，再从 `r_geo` 里减掉。这样换向时的「失动」不会被误判成 VLA 失败。

关键边界：如果关节编码器只在电机侧、没有输出侧/末端可观测的传动误差，或者没有力矩估计，这个模型只能解释「负载柔度」那一部分，不能解释全部滞回。产物区会把这个写成假设，并给出退化方案（只用扭矩代理 + 更宽的容差）。

### 2.2 流匹配的 ODE 路径是一张云端-边缘证书

流匹配策略把动作建模为 ODE：

```text
dx/dτ = v_θ(x, τ | o, u),   x_0 ~ N(0, I),   x_1 = a
```

云端用 `N_c` 步、`K` 个样本；边缘用缓存计划或少量步数。证书包含：

```text
L        = ∫ ||v|| dτ                       # 路径长度
C        = ∫ ||dv/dτ|| dτ / (L + ε)         # 归一化曲率
Δ_N      = ||Φ^N(x_0) − Φ^{N/2}(x_0)||      # 截断/求解器敏感性
A        = 1 − Var_k(a^(k)) / (σ_a^2 + ε)   # 多样本一致性
f_flow   = w_C C + w_N Δ_N + w_A (1 − A)
```

- **曲率小** ⇒ 计划局部近似直线，边缘可以用线性重锚把旧计划对齐到当前状态，误差 `O(C L (dΔt)^2)`。
- **曲率大** ⇒ 不要重锚；如果流分数不高，可以请求新计划；如果流分数高，交给 fallback/hold。
- **一致性低** ⇒ 语义多模态（例如「抓杯子还是抓盘子」），几何残差可能看不出来；这是流证书作为独立审计通道的价值。

### 2.3 残差分解与自审门

```text
r_raw   = r_pol + r_mech + r_stale + ε
r_w     = r_raw − r̂_mech − r̂_stale          # 白化残差
s_res   = Σ_k w_k z(r_w_k)                  # 残差分数
s_flow  = f_flow                            # 流证书分数
e_res   = 1[s_res > q_res]
e_flow  = 1[s_flow > q_flow]
e       = e_res ∨ (e_flow if audit enabled)
S_b     = max(0, S_{b−1} + e_b − α − k)
trigger = S_b > h
```

- `q_res, q_flow` 用**分通道** conformal 校准；不是把两个量加权成一个标量再校准。ZEST 的消融显示等权融合会稀释 OOD-S；分通道 + union bound 避免这个问题。
- 默认配置是 **CHORD-Core**：只用 `e_res`，流证书作为诊断和重锚决策。合成实验显示它主场景最好。
- 安全模式是 **CHORD-Flow**：`e_res ∨ e_flow`，用于过度白化风险高的场景（例如失败集中在换向）。合成实验显示它更鲁棒但主场景略贵。
- **自审**：维护一个窗口，若「残差惊讶率低」而「流异常率高」，说明解释器可能吞掉了失败；此时启用流交叉检查，或把解释器增益调低。

### 2.4 云端协同：瓶颈是时延，不是带宽

```text
Cloud:  o_c → flow ODE (N_c, K) → cert + plan
Edge:   plan + cert → staleness check → reanchor / defer → residual gate → WAVE-SERVO
```

- 时延 `d = floor((t_now − t_c) / Δt)`；用计划前缀从 `s_c` 前向仿真到当前，得到 `ŝ_d`；`δs = ||s_now − ŝ_d||` 进入 `r_stale`。
- 若 `C ≤ C_max` 且 `d ≤ d_max`：重锚，`d_eff = ρ d`（ρ<1），残差和时延惩罚都下降。
- 若 `C > C_max`：不重锚。若流分数不高（计划只是「旧」不是「坏」），请求新计划；若流分数高，交给信任门 fallback/hold，不要在 OOD 上浪费重规划预算。
- 证书只有几百个浮点数，带宽可忽略；真正要管的是延迟和丢包。丢包时用上一个计划 + 伺服；超过 `T_max` 则 hold。

### 2.5 失败模式分类

| 模式 | `r_pol` | `r_mech` | `r_stale` | `f_flow` | 可检测？ | 动作 |
|---|---|---|---|---|---|---|
| OOD-E 执行 | 高 | 可解释 | 可解释 | 高 | 是 | fallback / replan |
| OOD-S 语义（地图对） | 中/低 | 可解释 | 可解释 | 高（多模态） | 残差弱时靠流 | fallback / 流审计 |
| OOD-G grounding | 低 | 可解释 | 可解释 | 低 | **否** | hold / 外部语义 |
| 机构换向 | 低 | **高** | 低 | 低 | 不应触发 | 减掉，继续 |
| 云端延迟 | 低/中 | 低 | **高** | 低 | 不应触发 | reanchor / 等新计划 |
| 过度白化 | 低 | **被减掉** | **被减掉** | 可能高 | 需自审 | 启用流交叉检查 / 降增益 |

这张表是本轮的核心：它把「残差高」拆成六种情况，并明确 ZEST 会把前两种「良性高」误判为失败，而 CHORD 的收益来自「少误判」，不是「更敏感」。

## 3. 可证伪假设

| 编号 | 假设 | 证伪条件 | 级别 |
|---|---|---|---|
| H1 | 机构白化把 ID 假 fallback 降低 ≥3×，OOD AUROC 下降 ≤0.02 | 降低 <3× 或 AUROC 下降 >0.02 | 主 |
| H2 | 时延白化 + 重锚在云端延迟下提升成功率 ≥1pp 或降成本 ≥5%，ID 不回归 | 无提升或 ID 回归 | 主 |
| H3 | 流证书作为硬门控提升 OOD-S 成功率 ≥2pp，且不伤 OOD-E/ID | 无提升或 OOD-E 回归 | 主（本轮合成实验**未支持**，剪枝为诊断/安全模式） |
| H4 | 过度白化下 Core 退化，Flow 交叉检查能恢复；自审能检测到「残差安静 + 流异常」 | Core 不退化（说明风险不存在）或 Flow 不恢复 | 主（风险） |
| H5 | 失败残差与解释子空间的主角 >θ_min；否则不可检测 | 主角 <θ_min 且无流信号 | 主（可检测性边界） |
| H6 | 证书带宽可忽略，p99 由 ODE 推理和网络主导；重锚误差 ≤ 任务容差 | 证书/重锚成为瓶颈 | 次（工程） |

H3 是刻意写成「可能失败」的：本轮合成实验里，流硬门控在主场景没有净收益（OOD-S 变好，OOD-E 因为更早/更频繁的 fallback/probe 变差），所以默认配置剪枝为 CHORD-Core，流证书只做诊断和重锚。**一个不能证伪自己复杂度的方案，不值得工程化。**

## 4. 什么情况下放弃这条线

- 谐波零模型在真实 G1/Dex1 上的预测误差与残差信号同量级（透明/反光、未建模负载、温度漂移）→ 白化可能有害，退回 ZEST 的原始残差。
- 失败残差与解释子空间的主角 <10°，或 OOD 失败方差 >50% 被解释器吸收 → 过度白化是结构性的；不要继续调阈值，改用流交叉检查或独立语义信号。
- 流证书的曲率/截断/一致性在真实任务上 AUROC <0.65 → 剪掉流门控，只保留时延重锚。
- 云端延迟 p99 >150 ms 或重锚在接触阶段引入碰撞/超时 → 重锚只在 APPROACH/PRECONTACT/原语边界允许；否则只做诊断。
- 谐波参数随温度/磨损漂移，且无法周期性重标定 → 冻结模型失效；要么加在线鲁棒容差，要么放弃白化。
- 自审的假阳性高（把正常换向当成过度白化）→ 降低审计灵敏度，宁可保守也不要频繁切换。

## 5. 一句话押注

**第 15 轮对残差设阈值；本轮先用谐波减速器的物理零模型和云端-边缘时延零模型解释残差，再对解释不掉的部分设阈值，并用流匹配 ODE 证书做独立审计——让良性的机构/时延差异不再冒充策略失败，也让系统在解释器「过于安静」时知道要复查。**

## 6. 本轮最大的风险

**过度白化：当真实策略失败恰好发生在谐波减速器换向或云端计划过期的时间窗内，机构/时延解释器会把失败残差当成可解释项减掉；残差门安静，系统以受控的方式执行一个错误动作。** 合成实验把这个风险推到极限（失败只在换向发生、解释器偏差 1.0）：CHORD-Core 的 OOD fallback 率从 0.401 掉到 0.067，成功率 0.828，低于 ZEST 的 0.865；流交叉检查能把 fallback 率拉回 0.911，但主场景要付约 2pp 的成功率代价。这是低维解释器换低误报的结构性代价，不是调参能完全消除的。

## 2. 符号与形式化

### 2.1 谐波减速器的物理零模型

设关节 `j` 的电机侧角为 `q^m_j`，输出侧角为 `q^o_j`，减速比为 `N_j`，负载力矩为 `τ_j`，滞回记忆状态为 `m_j ∈ [-1,1]`。采用集总模型：

```math
q^o_j = \frac{q^m_j}{N_j}
      + \delta^{te}_j(q^m_j)
      + \delta^{hys}_j(\tau_j, m_j)
      + \delta^{fric}_j(\dot q^m_j, \tau_j)
      + \varepsilon_j
```

其中：

```math
\delta^{te}_j(q^m_j) = \sum_{l=1}^{L} a_{j,l}\sin(l q^m_j + \phi_{j,l})
```

```math
m_j \leftarrow \mathrm{clip}\!\left(m_j + \eta(\mathrm{sign}(\dot q^m_j) - m_j), -1, 1\right),
\qquad
\delta^{hys}_j = b_j m_j + \frac{c_j \tau_j}{K_j}
```

```math
\delta^{fric}_j = f^c_j \tanh(\dot q^m_j / v_0) + f^v_j \dot q^m_j
```

参数 `θ_j = (a_{j,\cdot}, φ_{j,\cdot}, b_j, c_j, K_j, f^c_j, f^v_j)` 在一条标定轨迹上辨识：慢速正弦、若干负载、正反向各一次。辨识完成后**冻结**；本轮不在线更新。它是物理模型/标定量，不是第二个学习策略。

给定指令 `q^c` 和测量 `q^o`，预测机构残差：

```math
e^{\mathrm{mech}}_j = q^o_j - \hat H_j(q^c_j, \tau_j, m_j)
```

末端笛卡尔机构残差用几何 Jacobian 一阶近似：

```math
r^{\mathrm{mech}} \approx J(q)\, e^{\mathrm{mech}} + O(\|e^{\mathrm{mech}}\|^2)
```

**假设 H-mech（必须写清）**：关节位置在输出侧可测，或输出侧误差可通过末端位姿观测；力矩 `τ_j` 可由关节力矩传感器/电流代理估计。若只有电机侧编码器且无力矩，模型退化为「负载柔度 + 摩擦」的近似，`r_mech` 只减掉可解释部分，剩余部分仍进入 `r_pol`；产物区把这一退化写成 G17 的失败条件。

### 2.2 流匹配策略与 ODE 证书

设 VLA 为流匹配策略 `v_θ(x, τ | o, u)`，`θ` 冻结。动作由 ODE 产生：

```math
\frac{dx}{d\tau} = v_\theta(x, \tau \mid o, u),
\qquad x_0 \sim \mathcal N(0,I),
\qquad x_1 = a
```

云端用 `N_c` 步、`K` 个初始噪声样本；边缘用缓存计划或少量步数。定义证书：

```math
L = \int_0^1 \|v_\theta(x_\tau,\tau)\|\,d\tau
```

```math
C = \frac{\int_0^1 \|\frac{d}{d\tau}v_\theta(x_\tau,\tau)\|\,d\tau}{L + \epsilon}
```

```math
\Delta_N = \left\|\Phi^{N}_1(x_0) - \Phi^{N/2}_1(x_0)\right\|
```

```math
A = 1 - \frac{\mathrm{Var}_{k=1..K}\!\left(a^{(k)}\right)}{\sigma_a^2 + \epsilon}
```

```math
f_{\mathrm{flow}} = w_C C + w_N \Delta_N + w_A (1-A)
```

证书 `cert = (x_0, a_{1:T}, \{(\tau_i, x_{\tau_i})\}, L, C, \Delta_N, A, t_c, \mathrm{hash}(s_c))`。它只有几百个浮点数，带宽可忽略；云端不需要传图像或大特征。

**流证书的三种用途**：

1. **时延重锚**：`C` 小 ⇒ 路径局部近似直线，线性重锚误差有界；`C` 大 ⇒ 不重锚。
2. **语义审计**：`A` 低 ⇒ 多模态/语义歧义，几何残差可能看不出来。
3. **过度白化审计**：`r_pol` 安静但 `f_flow` 持续高 ⇒ 解释器可能吞掉了失败。

### 2.3 云端-边缘协议与时延零模型

云端在 `t_c` 用状态 `s_c` 生成计划；边缘在 `t` 收到。定义延迟步数：

```math
d = \left\lfloor \frac{t - t_c}{\Delta t} \right\rfloor
```

用计划前缀 `a_{1:d}` 从 `s_c` 前向仿真机器人（确定性运动学 + 已知控制器模型），得到 `\hat s_d`。时延残差：

```math
r^{\mathrm{stale}} = K_s \left\| s_{\mathrm{now}} - \hat s_d \right\|
```

其中 `K_s` 是把状态差投影到残差通道的固定矩阵。若 `C ≤ C_max` 且 `d ≤ d_max`，重锚：把计划索引平移到当前相位，等效延迟 `d_eff = ρ d`（`ρ<1`）。重锚误差由 2.6 的 Taylor 界控制。若 `C > C_max`：

- 流分数不高（计划只是旧，不是坏）⇒ 请求新计划，支付 `c_replan`；
- 流分数高（OOD）⇒ 不重锚，交给信任门 fallback/hold，不在 OOD 上浪费重规划预算。

丢包/超时：用上一个计划 + 伺服；计划年龄 `> T_max` 则 `HOLD`。边缘从不阻塞等待云端。

### 2.4 残差分解

令原始残差向量 `r ∈ R^4`（`tmp, geo, goal, dyn`）。分解：

```math
r = r^{\mathrm{pol}} + r^{\mathrm{mech}} + r^{\mathrm{stale}} + \varepsilon
```

白化残差：

```math
r^{w} = r - \hat r^{\mathrm{mech}} - \hat r^{\mathrm{stale}}
```

残差分数用鲁棒尺度：

```math
z_k = \frac{r^w_k}{\sigma_k + \epsilon},
\qquad
s_{\mathrm{res}} = \sum_k w_k z_k
```

`σ_k` 用滑动 MAD（`1.4826 · MAD + ε`）或标定时的固定尺度。流分数 `s_flow = f_flow`。

### 2.5 分通道 conformal + CUSUM + 自审

用 ID 校准集分别取分位数：

```math
q^{\mathrm{res}}_\alpha = \mathrm{Quantile}_{1-\alpha_{\mathrm{res}}}\{s_{\mathrm{res}}^{\mathrm{cal}}\}
```

```math
q^{\mathrm{flow}}_\beta = \mathrm{Quantile}_{1-\beta}\{s_{\mathrm{flow}}^{\mathrm{cal}}\}
```

惊讶指示：

```math
e^{\mathrm{res}}_b = \mathbb 1[s_{\mathrm{res},b} > q^{\mathrm{res}}_\alpha]
```

```math
e^{\mathrm{flow}}_b = \mathbb 1[s_{\mathrm{flow},b} > q^{\mathrm{flow}}_\beta]
```

组合（默认 Core 只用 `e_res`；Flow 安全模式用并集；Audit 用条件）：

```math
e_b = e^{\mathrm{res}}_b \;\vee\; \left(\mathrm{audit}_b \wedge e^{\mathrm{flow}}_b\right)
```

CUSUM：

```math
S_b = \max(0, S_{b-1} + e_b - \alpha - k),
\qquad S_0 = 0
```

触发 `S_b > h` 进入 `FALLBACK`。复检/滞回继承 ZEST：每 `r` 个 fallback 块做一次 `SERVO` 探针；不惊讶则 `S_b←0` 回 `TRUST`；接触/搬运阶段禁止探针。

软胜任力：

```math
c_b = 1 - \frac{1}{W}\sum_{i=0}^{W-1} e_{b-i}
```

只进入 VOI 的成功模型，不直接触发门控。

**自审规则**：维护窗口 `W_a`，若

```math
\mathrm{rate}(e^{\mathrm{flow}}) > \tau_f
\quad\wedge\quad
\mathrm{rate}(e^{\mathrm{res}}) < \tau_r
```

则判定「解释器可能过度白化」，启用 `audit_b=1`（流交叉检查）并可选地把解释器增益乘以 `γ<1`。阈值 `τ_f, τ_r` 在校准集上选取，目标是 ID 上自审触发率 `≤1%`。

### 2.6 失败模式分类与可检测性边界

| 模式 | VLA | 地图目标 | `r_pol` | `r_mech` | `r_stale` | `f_flow` | 可检测？ | 动作 |
|---|---|---|---|---|---|---|---|---|
| OOD-E 执行 | 错 | 对 | 高 | 可解释 | 可解释 | 高 | 是 | fallback/replan |
| OOD-S 语义（地图对） | 错 | 对 | 中/低 | 可解释 | 可解释 | 高（多模态） | 残差弱时靠流 | fallback/流审计 |
| OOD-G grounding | 错 | 错 | 低 | 可解释 | 可解释 | 低 | **否** | hold/外部语义 |
| 机构换向 | 对 | 对 | 低 | **高** | 低 | 低 | 不应触发 | 减掉，继续 |
| 云端延迟 | 对 | 对 | 低/中 | 低 | **高** | 低 | 不应触发 | reanchor/等新计划 |
| 过度白化 | 错 | 对 | **被减掉** | **被减掉** | **被减掉** | 可能高 | 需自审 | 流交叉检查/降增益 |

这张表是本报告的核心：它把「残差高」拆成六种情况，并明确 ZEST 会把前两种「良性高」误判为失败；CHORD 的收益来自「少误判」，不是「更敏感」。

**算法步骤（总览）**

1. **离线标定**：在已知 ID 任务上辨识谐波参数 `θ_j`，冻结；收集 ID 白化残差与流分数，取 `q_res, q_flow`；冻结 `α, β, k, h, W, τ_f, τ_r`。
2. **云端**：给定观测，跑流匹配 ODE（`N_c` 步、`K` 样本），计算证书，发送计划 + 证书。
3. **边缘每块执行前**：用证书做时延检查；若 `C` 小且 `d` 小，重锚；若 `C` 大，按流分数决定等新计划或交给门控；给出允许动作集 `A_adm`。
4. **每块执行后**：计算 `r_tmp, r_geo, r_goal, r_dyn`；减掉 `r_mech, r_stale`；融合为 `s_res`；更新 `e_res`、`e_flow`、`S_b`。
5. **自审**：若残差安静但流异常，启用流交叉检查或降解释器增益。
6. **调度**：在 `A_adm` 上按 `Δ/cost` 选动作；`TRUST` 走 VOI-MAP，`FALLBACK` 走几何语法。
7. **复检**：`FALLBACK` 每 `r` 块做一次 `SERVO` 探针；不惊讶则回 `TRUST`。
8. **记录**：每块记录 `r_raw, r_mech, r_stale, r_w, s_res, s_flow, S_b, mode, action, cost, latency`；用于 G17–G20 的预注册分析。

```python
        self._update_gate(s_res, s_flow)

        # 5. action selection

        if act == "SERVO":

        if act == "LOOK":

        if act == "VLA":
```

### 3.3 谐波白化伪代码

```python
def harmonic_residual(obs, harmonic):
    # obs: q_motor, q_output (or q_output proxy), qdot, tau
    e = []
    for j in range(n_joints):
        qm = obs.q_motor[j]
        qo = obs.q_output[j]
        tau = obs.tau[j]
        m = harmonic.memory[j]
        qhat = (qm / harmonic.N[j]
                + harmonic.transmission_error(j, qm)
                + harmonic.hysteresis(j, tau, m)
                + harmonic.friction(j, obs.qdot[j], tau))
        e.append(qo - qhat)
        harmonic.memory[j] = clip(m + harmonic.eta[j] * (sign(obs.qdot[j]) - m), -1, 1)
    return harmonic.jacobian(obs.q) @ e      # Cartesian approximation

def staleness_residual(obs, plan, cert, dt):
    if cert is None:
        return zeros(4)
    d = int(floor((obs.t - cert.t_c) / dt))
    if d <= 0:
        return zeros(4)
    s_hat = forward_sim(cert.s_c, plan[:d])  # deterministic kinematic sim
    ds = obs.state - s_hat
    return cert.Ks @ ds

def whiten(r_raw, r_mech, r_stale):
    return r_raw - r_mech - r_stale
```

```python
def cloud_flow_certificate(v_theta, obs, N=20, K=4):
    x0 = sample_noise(K)
    traj = []
    for k in range(K):
        xs, vs = ode_solve(v_theta, x0[k], obs, N)   # x_1 = action
        traj.append((xs, vs))
    a = mean([t[-1] for t in traj])
    L = mean([path_length(vs) for _, vs in traj])
    C = mean([path_curvature(xs, vs) for xs, vs in traj])
    dN = mean([norm(ode_solve(v_theta, x0[k], obs, N)[-1]
                    - ode_solve(v_theta, x0[k], obs, N // 2)[-1]) for k in range(K)])
    A = agreement([t[-1] for t in traj])
    f = wC * C + wN * dN + wA * (1 - A)
    return Certificate(x0, a, checkpoints(traj), L, C, dN, A, obs.t, obs.state, f)

def maybe_reanchor(obs, plan, cert, dt):
    if cert is None:
        return plan
    d = int(floor((obs.t - cert.t_c) / dt))
    if d <= 0 or cert.C > C_MAX or d > D_MAX:
        return plan
    # linear re-anchor: align plan phase to current state
    k_star = argmin_k ||plan_state(plan, k) - obs.state||
    shift = max(0, d - k_star)
    return plan[shift:] + tail_extrapolate(plan, shift, cert)
```

```python
def update_gate(self, s_res, s_flow):
    e_res = int(s_res > self.q_res)
    e_flow = int(s_flow > self.q_flow)
    self.surprise_window.append(e_res)
    self.flow_window.append(e_flow)

    # self-audit: residual quiet but flow repeatedly anomalous
    if (len(self.flow_window) >= WA
            and mean(self.flow_window) > TAU_F
            and mean(self.surprise_window) < TAU_R):
        self.audit = True

    e = e_res or (e_flow if (MODE == "FLOW" or self.audit) else 0)
    self.cusum = max(0.0, self.cusum + e - ALPHA - K)
    if self.cusum > H:
        self.mode = "FALLBACK"
        self.fallback_dwell = 0
```

### 3.6 调度器与动作集

状态：

```math
x_b=(b_b,\ p_b,\ \phi_b,\ B_b,\ M_b,\ c_b,\ S_b,\ \mathrm{audit}_b)
```

动作与成本继承 ZEST/VOI-MAP：

| 动作 | 成本 | 作用 | 门控约束 |
|---|---|---|---|
| `SERVO` | `c_s` | 执行当前 VLA 块 | 仅 `TRUST`；`FALLBACK` 中仅复检探针 |
| `LOOK` | `c_l` | 主动视角，降低目标熵 | 两模式都可用；CONTACT 禁用 |
| `VLA` | `c_v` | 新计划/重新 grounding | 两模式都可用；异步 |
| `REANCHOR` | `c_r` | 用流证书把旧计划对齐到当前 | 仅 `C≤C_max, d≤d_max` |
| `FALLBACK` | `c_f` | 执行几何原语 | 仅域检查通过 |
| `COMMIT` | 0 | 停止收集信息，执行 MAP 目标 | `TRUST` |
| `HOLD` | 0 | 安全停止 | 无 fallback/预算耗尽/计划过期 |

成功模型（MAP 近似，继承 VOI-MAP，新增 reanchor）：

```math
P_{\mathrm{succ}}(\mathrm{SERVO}) \approx c_b\, b_{\max}\, f(p_b+\delta)
```

```math
P_{\mathrm{succ}}(\mathrm{REANCHOR}) \approx c_b\, b_{\max}\, f(p_b+\delta) - \lambda_C C
```

```math
P_{\mathrm{succ}}(\mathrm{FALLBACK}) \approx b_{\max}\, g_{\mathrm{prim}}\, f_{\mathrm{geo}}(p_b)
```

```math
P_{\mathrm{succ}}(\mathrm{VLA}) \approx
\bigl(c_b+(1-c_b)q_v\bigr)b_{\max}f(p_b)+\Delta_{\mathrm{plan}}
```

调度：

```math
a^\star=\arg\max_{a\in\mathcal A_{\mathrm{adm}}(S_b,\mathrm{audit}_b)}
\frac{\Delta_a}{c_a}
\quad\text{s.t.}\quad c_a\le B_b
```

若最大比值低于机会成本阈值 `λ`，或预算耗尽，则 `COMMIT`/`HOLD`。

### 3.7 与 WAVE-SERVO / VOI-MAP 的接口

- `SERVO`：调用第 13 轮 5 步块；虚拟力、TD-PC、相位阻抗表、限幅不变。
- `REANCHOR`：只改写计划索引/尾部外推，仍经 WAVE-SERVO；不新增执行通路。
- `FALLBACK`：几何原语通过同一 WAVE-SERVO 执行；原语参数来自 VOI-MAP 的语义地图。
- `VLA`：异步请求新计划；拿到后缓存，按 5 步切片。
- `LOOK`：小幅视角动作，受关节限位/速度限幅；只在 APPROACH/PRECONTACT。
- `COMMIT`/`HOLD`：保持或安全停止。
- **安全继承**：CHORD 只删除/改写计划，不新增执行通路；所有动作仍是第 13 轮安全集的子集。

### 3.8 状态机

```text
INIT → GROUND → TRUST ⇄ FALLBACK → (PROBE) → TRUST
                  │        │
                  │        └─→ primitive queue → WAVE-SERVO
                  └─→ VOI-MAP: SERVO / LOOK / VLA / REANCHOR / COMMIT
                                         │
                                         └─ edit_score>θ_e → RECOVER → GROUND
```

新增 `REANCHOR` 与 `AUDIT` 两个节点；`AUDIT` 不改变模式，只打开流交叉检查。`RECOVER` 仍回到 `GROUND`，区分「目标错」和「执行错」。

### 3.9 `get_action` 的异常与并发规则

- 任何异常 → 返回上一合法 chunk 或安全 hold；绝不返回 NaN/错误形状。
- 每个端口独立维护地图、信念、预算、CUSUM、解释器状态；无跨端口共享。
- 云端证书缺失/过期 → 用旧计划 + 伺服；超过 `T_max` 则 `HOLD`。
- 谐波模型输入缺失（无力矩/无输出侧编码器）→ 只用可解释部分，剩余进入 `r_pol`；不阻塞。
- `REANCHOR` 只在 `C≤C_max, d≤d_max, phase∈{APPROACH,PRECONTACT}` 或原语边界允许；CONTACT/CARRY 禁止。
- `AUDIT` 触发后至少保持 `W_a` 个块，避免抖动。

## 4. 性质、复杂度与正确性

### 4.1 标签无关性与单模型合规

**命题 1（无监督信号）**：`r_mech` 只使用 `(q^c, q^o, τ, m)`；`r_stale` 只使用 `(cert, s_c, s_now, plan, t)`；`f_flow` 只使用同一个 VLA 的 ODE 轨迹；conformal 分位数只使用 ID 残差；CUSUM 是 `e_b` 的确定性递推。没有任何一步读取成功标签 `y`。

**证明**：由构造直接得到。谐波参数由标定轨迹的输入-输出辨识，不使用任务成功标签；流证书由 `v_θ` 的 ODE 计算；`q_res, q_flow` 是 ID 残差的经验分位数；`S_b` 是 `e_b` 的递推。∎

**单模型合规**：唯一的策略网络是 `v_θ`。谐波模型是低维物理模型（每关节 3–8 个参数），时延模型是确定性前向仿真，流证书是同一网络的 ODE 元数据。若评审认为「参数辨识」算学习，可把参数固定为厂商标定值/一次性标定值，不再在线更新；conformal/CUSUM 是一维统计，不是学习模型。

### 4.2 ID 假警报控制

**命题 2（分通道 split conformal）**：设校准残差 `s^{res}_1..s^{res}_n` 与测试残差 `s^{res}_{n+1}` 在 ID 下可交换，`q^{res}_α` 取第 `⌈(n+1)(1-α_res)⌉` 个次序统计量；流分数同理取 `q^{flow}_β`。则

```math
\Pr(e^{\mathrm{res}}=1)\le \alpha_{\mathrm{res}},
\qquad
\Pr(e^{\mathrm{flow}}=1)\le \beta
```

由 union bound：

```math
\Pr(e=1)\le \alpha_{\mathrm{res}}+\beta
```

**证明**：标准 split conformal（Vovk et al., 2005；Angelopoulos & Bates, 2023）+ 并集界。∎

**读法**：默认 Core 只用 `e_res`，取 `α_res=0.12`；Flow 安全模式取 `α_res=0.10, β=0.02`；Audit 只在自审触发时用 `e_flow`，其条件触发率由 `τ_f, τ_r` 控制。CUSUM 在 ID 下是带负漂移 `-(α+k)` 的随机游走；`h` 越大平均运行长度越长，近似指数增长（Page, 1954；Lorden, 1971）。本报告不给精确 ARL 公式；正式评测前用校准集模拟。

**边界**：这是边际保证，不是条件保证；若校准集与测试不可交换（真实 OOD），保证失效，靠 CUSUM 和在线尺度兜底。

### 4.3 OOD 检测延迟

**命题 3（CUSUM 延迟）**：若 OOD 下 `e_b` 独立同分布 `Bernoulli(α')`，且 `α'>α+k`，则

```math
\mathbb E[\tau]\approx \frac{h}{\alpha'-\alpha-k}+O(1)
```

**证明**：带正漂移随机游走首次越过 `h` 的标准 CUSUM 近似（Lorden, 1971）。∎

**读法**：白化把 ID 残差的方差降下来，`q_res` 变低；同样的 OOD 严重度对应更大的 `α'`，检测更快。合成实验的校准分位数就体现了这一点：ZEST `q_res=0.526`，CHORD-Core `q_res=0.297`。流通道如果启用，提供独立的惊讶源；但也会引入额外的误报，需要分通道校准。

### 4.4 解释器分离性

**命题 4（子空间分离）**：令 `U_ex = span{mechanism basis} + span{staleness basis}`。若策略失败残差 `r_pol` 与 `U_ex` 的主角为 `θ`，则白化后至少保留

```math
\|P_{U_{\mathrm{ex}}^\perp} r^{\mathrm{pol}}\| \ge \sin\theta\,\|r^{\mathrm{pol}}\|
```

**证明**：`r^w = P_{U_ex^\perp} r_pol +` 解释器估计误差；正交投影的范数下界为 `sinθ ||r_pol||`。∎

**读法**：`θ` 是「失败有多少落在解释器能解释的方向之外」。`θ` 越大，白化越安全；`θ→0` 时，失败完全落在机构/时延子空间内，任何只依赖残差的检测器都无法区分它与良性解释项。这是本轮的可检测性边界，也是过度白化的理论根源。`θ` 可以在一个小规模 OOD 验证集上估计：对失败残差协方差做 PCA，计算其主方向与 `U_ex` 的主角；若最小主角 `<10°`，剪掉解释器或启用流交叉检查。

### 4.5 过度白化界

设解释器估计为 `\hat h = h + b`，`b` 是标定偏差（标定集污染、模型失配、温度/磨损）。白化后的失败分量为：

```math
r^{w}_{\mathrm{pol}} = r^{\mathrm{pol}} - P_{U_{\mathrm{ex}}} b
```

若 `\|P_{U_ex} b\| \ge \|P_{U_ex} r_pol\|`，失败在解释子空间内的分量被完全遮住；子空间外的分量仍然可见。因此：

```math
\text{检测损失} \le \|P_{U_{\mathrm{ex}}} b\| / \|r^{\mathrm{pol}}\|
```

**缓解**：

1. **冻结参数 + ID-only 标定**：把 `b` 限制在模型近似误差，而不是在线适应 OOD。
2. **解释器增益上限**：只减掉不超过标定残差 95% 分位数的量，避免把大残差整体吞掉。
3. **自审**：残差安静 + 流持续异常 ⇒ 启用交叉检查或降增益。
4. **独立信号**：流一致性、跨指令一致性、任务清单约束；本轮只做流一致性。

### 4.6 重锚误差界

设流场 `v` 关于状态 Lipschitz、曲率 `C`，计划在延迟 `dΔt` 内用线性外推。Taylor 余项给出：

```math
\|a_{d} - a^\star(s_{\mathrm{now}})\|
\le \frac12 C L (d\Delta t)^2 + O((d\Delta t)^3)
```

**读法**：`C` 小、`d` 小 ⇒ 重锚误差可控；`C` 大 ⇒ 线性外推失效，应等新计划或交给门控。这个界是 `C_MAX, D_MAX` 的设计依据，不是精确保证；真实流场可能不满足全局 Lipschitz，需在 G18 上实测。

### 4.7 安全、无源性与谐振

- **门只删/改计划**：CHORD 的输出动作集是第 13/14 轮安全集的子集；`REANCHOR` 只改计划索引，仍经 WAVE-SERVO；`FALLBACK` 走同一执行通路。ZEST 的安全继承不变。
- **谐振**：谐波减速器的扭转谐振 `ω_j = sqrt(K_j/I_j)`。边缘可对动作谱在 `ω_j` 附近加 notch/低通；若滤波器在 `ω_j` 的增益有界、相位滞后在 WAVE-SERVO 的无源裕度内，则不破坏无源性。这是设计条件，不是完整证明；G18 测 p99 和关节限幅。
- **边界**：这保证「控制器安全」，不保证「任务安全」。几何原语选错目标或碰撞仍由语义地图/自由空间检查负责。

## 5. 本轮合成实验（实跑，B 级证据）

### 5.1 这不是基准证据

这是一个**合成机制检查**，只回答一个问题：在「ID 胜任、OOD 不胜任；谐波机构残差在换向时升高；云端计划有 per-episode 延迟；流证书有曲率/截断/一致性；fallback 有成功率/成本」的玩具模型里，残差分解是否比 ZEST 的原始残差更少误报、更准检测，以及过度白化的边界在哪里。它不证明真机收益，也不证明谐波参数在真实 G1/Dex1 上可辨识。脚本：`exp/chord_sim.py`；结果：`exp/chord_results.json`。

```text
  f_flow = 1.5C + 1.0Δ_N + 0.5(1-A)。
- 残差：base(type) + m_true + s_true + noise；CHORD 减掉 m_hat、s_hat。
- 门控：分通道 split conformal + CUSUM（α=0.12, k=0.05, h=2.5）；
  Core：q_res 取 ID 88% 分位；Flow：q_res/q_flow 各取 94% 分位；
  Audit/Gate：q_res 取 90%，q_flow 取 98%，条件启用。
- 主表每格 6000 episodes；校准 5000；过度白化每格 3000；固定种子。
- Oracle 使用真实 c_true/g_true，忽略长期影响；不是 POMDP 最优。
```

**重要简化**：VLA 在玩具里只是每步成功概率，没有建模 30 步块内的时序结构、长程重规划、真实图像/深度；残差是标量代理，不是真实几何前端；谐波模型是标量代理，不是真实关节参数；流证书是标量代理，不是真实 ODE。因此实验对 VLA 和 CHORD 都是**保守的**，不能据此否定真实系统的长程价值。

### 5.5 过度白化/校准偏差结果

场景：OOD 失败**只**发生在换向（confounding），失败残差完全落在机构子空间；`bias` 是解释器幅度的高估量（标定污染/模型失配）。这是对抗性场景，用来验证命题 4/4.5 的边界。

| 0.00 | ZEST | 0.865 | 0.525 | 0.401 |
| 0.00 | Core | 0.864 | 0.614 | 0.403 |
| 0.00 | Flow | 0.909 | 0.601 | 0.914 |
| 0.40 | ZEST | 0.865 | 0.525 | 0.401 |
| 0.40 | Core | 0.865 | 0.684 | 0.431 |
| 0.40 | Flow | 0.909 | 0.683 | 0.914 |

| 0.80 | Flow | 0.909 | 0.675 | 0.914 |

**读法**：

- 这是本轮最重要的负面结果。解释器偏差从 0 增到 1.0 时，Core 的 OOD fallback 率从 0.403 掉到 **0.067**，成功率从 0.864 掉到 **0.828**，低于 ZEST 的 0.865。失败被解释器当成机构项减掉了，残差门安静。
- Flow 的独立流通道把 fallback 率保持在 0.911、成功率 0.909，说明**流证书是对抗过度白化的有效独立信号**；代价是主场景约 2pp 的成功率（见 5.3）。
- Audit（条件流交叉检查）只部分恢复（0.335/0.842），因为自审需要几个块才能积累证据；短 episode 在触发前已经失败。它是有希望的折中，但本轮不作为默认。
- 这个场景的 AUROC 很低（ZEST 0.525）是因为用「首步残差」做 AUROC，而失败只在换向的少数步出现；这提醒我们：**稀疏、时变的失败不能用首步 AUROC 评价**，G19 要用「块级检测延迟/漏报率」。

| 变体 | 机制白化 | 时延白化/重锚 | 流通道 | ρ=0 成功率 | ρ=0.25 成功率 | ID fallback (ρ=0.25) | AUROC (ρ=0.25) |
|---|---|---|---:|---:|---:|---:|---:|
| ZEST | 否 | 否 | 否 | 0.915 | 0.902 | 0.020 | 0.880 |
| NoMech | 否 | 是 | 是 | 0.899 | 0.891 | 0.003 | 0.892 |
| NoStale | 是 | 否 | 是 | 0.923 | 0.907 | 0.013 | 0.908 |
| **Core** | 是 | 是 | 否 | **0.921** | **0.913** | **0.005** | **0.916** |
| Flow | 是 | 是 | 是 | 0.898 | 0.890 | 0.003 | 0.913 |

**读法**：

- 机制白化主要降 ID 误报（0.020→0.005）并提 AUROC；去掉它（NoMech）在 ρ=0 掉 2.2pp，在 ρ=0.25 掉 2.2pp。
- 时延白化/重锚主要在时延场景和 ID 误报上起作用；去掉它（NoStale）在 ρ=0 反而略高（0.923 vs 0.921），说明在无延迟的静态场景它有轻微过白化/过拟合；在 ρ=0.25 和时延场景 Core 更好。
- 流硬门控（Flow）在主场景不划算；它的价值在过度白化场景（5.5）。
- 这些差异是合成实验的，不能直接外推到真机；G17/G18 要逐项验证。

### 5.7 读法：哪些假设被支持，哪些没有

**被支持**：

- **H1（机制白化）**：ID 假 fallback 0.020–0.023 → 0.004–0.005（约 5×），AUROC 不降反升；ρ=0 时 0.964→0.997，ρ=0.25 时 0.880→0.916，ρ=0.5 时 0.784→0.839。
- **H2（时延白化 + 重锚）**：时延场景成功率 0.914→0.926，成本 5.75→5.61，ID 假 fallback 0.019→0.000。
- **H4（过度白化风险）**：Core 在解释器偏差 1.0 时 fallback 0.067、成功率 0.828，低于 ZEST 的 0.401/0.865；流交叉检查恢复到 0.911/0.909。风险与缓解都可见。
- **H5（分离性边界）**：confound 场景把失败放在解释子空间内，Core 失效；这验证了命题 4 的 `θ→0` 边界。

**没有被支持 / 被证伪**：

- **H3（流硬门控）失败**：主场景 Flow 0.890 vs Core 0.913（ρ=0.25）；OOD-S 的 fallback 变好，但 OOD-E 因為更早/更频繁的 fallback/probe 变差，净负。**结论：默认配置剪枝为 Core；流通道只作为诊断、重锚决策和 Audit 安全模式。**
- **Audit 的净收益不足**：confound 场景 Audit 0.842 vs Flow 0.909；自审需要多个块积累证据，短 episode 来不及。列为 G19 的候选，不作为默认。
- **Always-FALLBACK 被支配**：ID 和静态 OOD 都差于 Core/Flow；不能替代门控。
- **OOD-G 仍不可检测**：ρ=0.5 时所有策略的 AUROC 都被静默 OOD 拉低；Core 0.839 仍不是「解决」，只是比 ZEST 好。

### 5.8 效度威胁

| 威胁 | 影响 | 下一轮怎么补 |
|---|---|---|
| 残差是标量代理 | 没测试真实几何前端（视差、光流、透明/反光） | G17：真实/半真实桌面，注入位姿噪声与遮挡 |
| 谐波模型是标量代理 | 可能高估白化收益 | G17：真实 G1/Dex1 关节标定，测预测误差 |
| 流证书是标量代理 | 没测试真实 ODE 曲率/截断/一致性 | G20：真实流匹配策略，测 AUROC 与延迟 |
| 时延是 per-episode 常数 | 真实延迟可能抖动/突发 | G18：注入抖动、丢包、突发延迟 |
| fallback 成功率是类型设定的 | 可能高估/低估降级收益 | G18/G19：按原语统计真实成功率 |
| VLA 只建模为每步成功概率 | 低估长程重规划/时序结构 | 加入 30 步块、重叠计划、真实延迟 |
| 过度白化是对抗性场景 | 真实失败未必只在换向 | G19：统计真实 OOD 失败与换向的相关性，估计主角 |
| 无真机 | 不能证明物理接触安全 | 保留第 13 轮限幅/重试；G18 真机 A/B |
| 首步 AUROC 不适合稀疏失败 | confound 的 AUROC 偏低 | G19 用块级检测延迟/漏报率/恢复率 |

## 7. 风险与合规

### 7.1 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 确定性物理 | 谐波模型、时延前向仿真、重锚 | 最低 | 主推 |
| C2 符号 backchannel | 相位/子目标符号由几何/夹爪派生 | 低 | 主推 |
| C3 同 checkpoint 特征 | 流证书用 VLA 自己的 ODE | 低 | 主推 |
| 禁止 | 第二个学习检测/分割/语言模型；在线学习谐波参数；训练失败检测器 | 高 | 不做 |

**关键声明**：CHORD 不训练任何新参数；谐波模型是标定量，时延模型是确定性仿真，流证书是同一 VLA 的 ODE 元数据；conformal/CUSUM 是一维在线统计。若评审认为「在线更新分位数」也算学习，可退化为固定标定分位数 + 固定 CUSUM 参数。

### 7.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| **过度白化** | 失败落在机构/时延子空间，被减掉，门控漏报 | 冻结参数、增益上限、自审、流交叉检查、G19 |
| **OOD-G 不可检测** | 目标错时系统自信执行 | 命题 7 边界；独立语义检查/任务清单；不承诺解决 |
| 谐波模型失配 | 透明/反光、温度/磨损导致预测误差大 | 只用可解释部分；在线容差；G17 失败即退回 ZEST |
| 标定集污染 | 解释器吸收 OOD 失败 | ID-only 标定；主角审计；增益上限 |
| 云端延迟/丢包 | 计划过期、重锚失效 | 证书时间戳；超时 hold；G18 |
| 重锚接触阶段碰撞 | 接触/搬运时改计划危险 | 重锚只在 APPROACH/PRECONTACT/原语边界 |
| 流证书太贵/太弱 | 云端 ODE 成本或 AUROC <0.65 | 只做诊断；G20 失败即剪枝 |
| 自审假阳性 | 正常换向被当成过度白化 | 提高 `τ_f`，降低审计灵敏度 |
| 谐振滤波滞后 | 破坏 WAVE-SERVO 无源裕度 | 只在 `ω_j` 附近 notch；G18 测 p99/限幅 |
| 统计假阳性 | 把噪声当涨点 | 预注册、配对、分层、Holm、阴性台账 |
| 引用污染 | 假文献支撑真结论 | 引用审计；`UNVERIFIED` 排除 |

### 7.3 已知失效模式

| 场景 | 会发生什么 | 门控行为 | 结果 |
|---|---|---|---|
| 失败只在换向（过度白化） | 解释器把失败当机构项减掉 | 残差安静，不触发 | **自信地错**；需流交叉检查/自审 |
| 透明杯子（OOD-G） | 立体视觉失败，地图和 VLA 一起错 | 残差/流都像 ID | **自信地抓错**；只能靠外部语义 |
| 未见物体颜色（OOD-E） | VLA 动作不匹配外观 | 残差高，触发 fallback | 几何原语 reach/grasp；可能成功 |
| 未见空间关系（OOD-S，地图对） | VLA 语义错，几何平滑 | 残差弱时靠流多模态 | fallback/审计；可能成功 |
| 云端延迟（非 OOD） | 计划旧，残差高 | 时延白化 + 重锚 | 继续执行；不误 fallback |
| 谐波换向（非 OOD） | 失动，残差高 | 机构白化 | 继续执行；不误 fallback |
| 传感器噪声尖峰 | 残差瞬变 | self-normalized + CUSUM | 不误触发 |
| 变形任务 FoldTowel | 语法不覆盖 | 域检查判 `semantic` | VLA/HOLD；不盲目降级 |

## 9. 一句话押注

**第 15 轮对残差设阈值；本轮先用谐波减速器的物理零模型和云端-边缘时延零模型解释残差，再对解释不掉的部分设阈值，并用流匹配 ODE 证书做独立审计——让良性的机构/时延差异不再冒充策略失败，也让系统在解释器「过于安静」时知道要复查。**

## 10. 本轮最大的风险

**过度白化：当真实策略失败恰好发生在谐波减速器换向或云端计划过期的时间窗内，机构/时延解释器会把失败残差当成可解释项减掉；残差门安静，系统以受控的方式执行一个错误动作。** 合成实验把这个风险推到极限（失败只在换向发生、解释器偏差 1.0）：CHORD-Core 的 OOD fallback 率从 0.403 掉到 0.067，成功率 0.828，低于 ZEST 的 0.865；流交叉检查能把 fallback 率拉回 0.911，但主场景要付约 2pp 的成功率代价。这是低维解释器换低误报的结构性代价，不是调参能完全消除的。
