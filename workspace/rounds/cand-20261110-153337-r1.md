# 第 44 轮（新循环第 4 轮） · Delay-Cert × MPC-Cert：把「通信延迟」与「模型预测控制」纳入可验证证书闭环（四层架构 v9）

> 承接第 43 轮 v20（Persona-Cert × Concurrent-Cert）。v20 把并发与租约写进证书，但它的租约模型仍压着两个未言明的单点假设：**(H1) 通信延迟只是让「已测得的标量边际」随时间线性衰减**——延迟越大，一切结论越保守，最终可用性崩塌；**(H2) 证书是一个「此刻安全/不安全」的标量判决**——它不含未来，因此只能被动收缩，无法主动吸收延迟。本轮灵感词「通信延迟」「模型预测控制」正好击中这两点：**通信延迟**迫使我们把延迟从「衰减项」提升为证书的语义坐标（端到端合成、乱序、分区、分布漂移）；**模型预测控制**提供了 v20 缺少的东西——**前瞻**。MPC 的可行域、终端不变集与 tube 天然就是一份「未来 N 步都安全」的证明对象，于是可以把安全证书从「标量边际」升级为「漏斗证书」，让**安全与延迟解耦，只让性能随延迟退化**。一句话：**延迟吃掉裕度，前瞻把裕度买回来；安全交给不变集，性能交给计划。**

## 0. 直觉与动机

### 灵感 1（通信延迟 → 延迟不是抖动，而是证书的坐标轴）

直觉上，v20 的租约 m−λ(t−τ) 只回答「这条结论离测量时刻过了多久」，却默认 τ 就是「本机刚测得」。真实系统里，一条远端证书的寿命由三段延迟组成：观测上传、远端计算、指令/计划下发；它还可能乱序、重复、丢失，甚至遇到分区。于是延迟不是标量噪声，而是**证书的一个坐标轴**：同一份计划在不同到达时刻含义完全不同。正确的处理不是「延迟越大越保守」这一条单调收缩，而是把延迟显式建模成**端到端延迟契约** δ_e2e（max/p99/抖动/违约概率/时钟同步误差），沿路径保守合成；当延迟无界（分区/未知网络）时直接令 δ=∞，不签发任何跨网证书，退回纯本地。这样延迟只影响「计划还能不能用」，而不再偷偷污染「此刻安不安全」。

### 灵感 2（MPC → 可行性即证书，前瞻即抗延迟）

直觉上，MPC 不只是控制器，它每解一次 QP 都顺带产出一个**证明对象**：名义轨迹、tube、终端不变集。如果优化可行，就存在一条未来 N 步都满足约束、并最终进入终端安全集的计划。这恰好是通信延迟需要的：**标量边际会随延迟过期，但一份带终端不变集的计划不会因为「晚到 80ms」就变成不安全**——只要到达时真实状态仍落在它的漏斗里，计划就仍然可执行；若落不进去，就执行本地安全内核 fallback。更关键的是，MPC 的模型还能做**延迟补偿预测**：远端在计划签发时把状态前推到预计到达时刻（Smith predictor 的非线性推广），使「晚到的计划」变成「正点到达的计划」。于是延迟被主动吸收，而不是被动收缩。安全性的真正来源收敛为两个**延迟无关**的对象：tube 的 RPI 声性和终端/可恢复域的归纳不变性。

### 灵感 3（耦合 → 安全/性能解耦与「三预算」）

直觉上，延迟、速度、前瞻是一组互相兑换的预算：延迟越大，预测误差越大，计划越可能落不进 tube；要保证可用，只能降速（减小预测误差）或加长前瞻（给到达后留更多剩余步）。因此「用户要快」不能被当成一句直接改 v_max 的特权——它必须通过**本地推理降低 δ**或**更多算力提高 N**来兑现，否则就是无证的扩张。这把第 43 轮的人格契约从「只收缩动作集」进一步收紧为「也不得越过延迟-速度-前瞻的可行性曲面」。同时，并发（v20）在这里获得新含义：多任务的证书流水线共享网络带宽与 horizon，按关键级分配；过载时先砍个性化与投机，硬保安全内核与 heartbeat。

### 耦合升级（v8 → v9）

v8 的核心是「收缩免费、扩张持证 + 并发 rely-guarantee + 租约新鲜度」。v9 在其上再加一层：**计划级安全用延迟不变的漏斗证书，状态级边际继续用租约；两者组成两级证书，漏斗不能覆盖租约的否决。** DCE（延迟补偿预测）把跨网状态前推到到达时刻；DIMC（延迟不变 MPC 证书）把 MPC 的可行性编译成漏斗 + 安全内核；CPP（证书流水线协议）负责 horizon deadline、乱序与关键级带宽；NLV（网络在环验证器）用延迟/抖动/丢包/分区/模型失配做压力测试。四层架构由 v8 的「人格契约 + 并发证书」升级为 v9 的「人格契约 + 并发证书 + **延迟契约 + 前瞻证书**」。

## 1. 形式化定义（增量：定义 44–50）

**定义 44（通信延迟契约与端到端合成）**：有向链边 e=(i→j) 的延迟契约 δ_e=(δ_max, δ_p99, J, γ, s)：δ_max 为硬上界、δ_p99 为高分位、J 为抖动、γ 为违约概率、s 为时钟同步误差。路径 P 的契约保守合成：

  δ_max(P)=Σ_e δ_max(e)，J(P)=Σ_e J(e)，γ(P)=1−Π_e(1−γ(e))，s(P)=Σ_e s(e)。

**单调性**：逐分量更小则路径契约更小；任何估计误差只能往大取。**未知即无穷**：无法给出有限 δ_max 时记 δ=∞，系统进入纯本地模式。**注**：soundness 只用 δ_max；δ_p99 仅用于性能与前瞻选型，且必须被 δ_max 夹住（不得越过硬上界）。

**定义 45（延迟补偿预测与预测误差域）**：远端在 τ 时刻已知模型 f、最后确认状态 x_{t0}、在途计划 π_inflight 与已执行输入序列，用**延迟补偿预测器**前推到预计到达时刻 t_a=τ+δ：

  x̂_{t_a} = f^{⌈δ/Δt⌉}(x_{t0}, π_inflight)（模型前推 + 已知输入重放）。

真实状态与预测之差 e_pred=x_{t_a}−x̂_{t_a} 属于**预测误差域** E_pred(δ)。鲁棒版取 E_pred(δ)=Reach_δ(W⊕E_model)；共形版用历史 (δ,e_pred) 样本给出 E_pred^α(δ)，在可交换性下覆盖 ≥1−α。**保证可用条件**：E_pred(δ,v_max) ⊆ Z（定义 46 的延迟无关 RPI tube），则延迟计划到达时**保证可执行**；否则计划可能被拒。**关键分离**：Z 不含 δ，δ 只进入 E_pred 与可用性——因此**安全性不依赖 δ，只依赖 Z 的声性**；延迟误差只造成可用性/性能损失，不造成静默不 sound。

**定义 46（Tube、安全内核与可恢复域）**：误差动力学 e_{t+1}=A_K e_t+w_t，w∈W，模型误差 E_model；Z 为辅助反馈 u=v+K(x−z) 下的鲁棒正不变（RPI）集，故 x_t∈z_t⊕Z 一旦成立便在计划期间永久成立。**安全内核** K=(Ω,κ_f)：Ω 控制不变于本地 fallback κ_f，Ω⊆X_safe，κ_f 不依赖网络。**可恢复域** R：存在本地恢复策略 κ_rec，使 ∀x∈R，κ_rec 在保持 X_safe 的同时有限步进入 Ω。**认证域** D=Ω∪R，系统归纳不变式要求 x_t∈D 始终成立。约束收紧：X_tight=X_safe⊖Z，U_tight=U⊖KZ；终端集 X_f=Ω⊖Z。

**定义 47（漏斗证书与延迟不变安全定理）**：τ 时刻为预计到达时刻 t_a 签发漏斗证书

  c=(π, z_{t_a..t_a+N}, F, Ω, R, κ_f, κ_rec, τ, t_a, N, δ_max, seq)，

其中 π 为名义输入序列、z 为名义轨迹，漏斗

  F(k)={ x : x∈z_{t_a+k}⊕Z，且从 x 出发执行 π 的第 k..N 步并施加 K 后，在 X_tight×U_tight 下可于 N−k 步内进入 z_{t_a+N}⊕Z 并最终进入 Ω }。

**定理（延迟不变安全）**：若 c 声（Z 包含全部 W⊕E_model 诱导误差、Ω 对 κ_f 不变、R 对 κ_rec 可恢复），且归纳前提 x_t∈D 成立，则对任意实际到达 t_a'≥τ 与实际状态 x_{t_a'}：
(i) 若 t_a'−t_a ≤ (N−k)Δt 且 x_{t_a'}∈F(k)，执行计划后 x 恒在 X_safe；
(ii) 否则若 x_{t_a'}∈R，执行 κ_rec，保持 X_safe 并有限步入 Ω；
(iii) 否则若 x_{t_a'}∈Ω，执行 κ_f，保持 Ω；
(iv) 若 x_{t_a'}∉D，拒绝执行计划并进入最后手段的认证急停（不在本定理保证内，必须由系统设计排除）。
**推论（安全/性能解耦）**：延迟 δ 只改变 (i) 是否成立（可用性），不改变 Z/Ω/R 的声性；故可用性随 δ 单调不增，安全性对 δ 不变（在归纳前提成立下）。**证**：对剩余步数归纳——tube 的 RPI 性保证误差不越出 Z，收紧约束保证名义轨迹安全，终端 Ω 不变性收尾；分支 (ii)(iii) 由 κ_rec/κ_f 定义直接给出。

**定义 48（前瞻-延迟匹配与 horizon deadline）**：Δt 为控制周期，δ_max 为硬延迟上界。为使计划到达时至少还有 N_use 步可用，需

  N ≥ ⌈δ_max/Δt⌉ + N_use。

第 k 步的 **horizon deadline**：D_max(k)=(N−k)Δt−δ_p99；D_max(k)<0 时计划必然在 horizon 内过期，必须拒用并触发重规划/fallback。**流水线规则**：当剩余可用步 ≤N_use/2 时启动下一份计划；下一份计划最迟签发时刻为 NΔt−⌈δ_p99/Δt⌉。**命题（无饥饿）**：若 N 满足上式且每份计划在 deadline 前发出，则任意时刻都有一份计划可覆盖至少一步，除非网络分区（此时 fallback 接管）。

**定义 49（共形延迟上界、自适应前瞻与三预算权衡）**：对路径延迟样本 {δ_i} 做 split conformal，得分=δ，得 D^α（第 ⌈(n+1)(1−α)⌉ 个次序统计量），可交换性下 P(δ≤D^α)≥1−α。**自适应前瞻**：N_t=clip(⌈D^α_t/Δt⌉+N_min, N_min, N_max)。**漂移检测**：滑动窗经验覆盖 <1−α−ε 或 ADWIN/KS 显著时，将 N 提到 N_max、速度上限降到 v_safe 并进入保守模式；连续窗口重新达标才恢复。**三预算权衡**：延迟预算 δ、速度预算 v_max、前瞻预算 N 必须同时满足

  E_pred(δ, v_max) ⊆ Z  ∧  N ≥ ⌈δ_max/Δt⌉ + N_use。

因此「用户要快」只能通过降低 δ（本地推理/边缘计算）或提高 N（算力/时延）兑现；**人格契约不得直接把 v_max 放大越过该式**，否则扩张无证。

**定义 50（两级证书层级与顺序一致性）**：系统同时维护 **L1 快租约**（v20 定义 41，状态相关边际的时效证书，毫秒级、延迟敏感）与 **L2 慢漏斗**（计划级安全证书，百毫秒级、延迟不变）。**使用规则**：动作 a 被允许 ⇔ L1 租约有效 ∧（L2 漏斗成员 ∨ fallback 分支）。L2 不得覆盖 L1 的否决（几何边际不足时，漏斗再宽也不能放行）；L1 失效时只能单调降级。**顺序一致性**：计划与证书带单调 seq 与路径向量时钟；接收端只接受 seq 更大的计划，旧计划可安全执行但不得回写覆盖新计划；乱序/重复到达时 per-generation last-writer-wins，且**合并只允许收缩**（新约束只能使允许动作集变小）。**命题**：任意乱序/重复/迟到下，若每次执行都满足两级规则，则安全集不因消息顺序而扩大，sound 性保持。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-60 DELAY-INVARIANT-MPC-CERTIFICATE（延迟不变 MPC 证书 DIMC）

1. **Tube 与安全内核构建**：离线求 RPI Z、认证 Ω/κ_f、可恢复域 R/κ_rec；运行期只做成员检查与收紧查表，避免在线重算。
2. **延迟补偿预测器**：按定义 45 用模型 + 在途计划 + 已知输入把状态前推到 t_a；输出 x̂_{t_a} 与 E_pred(δ,v_max)，并对 E_pred 做共形校准。
3. **漏斗证书编译**：鲁棒 tube MPC（收紧约束 X_tight/U_tight、终端 Ω）；输出 plan + funnel + (τ,t_a,N,δ_max,seq) 元数据；不可行时只发 FallbackOnly(Ω,κ_f)。
4. **使用期重定基与守卫**：到达时算 k=⌊(t−t_a)/Δt⌋，查 x∈F(k)；在漏斗内执行计划，否则按 R→κ_rec、Ω→κ_f 降级；均不可用则认证急停。
5. **保证可用闸门**：E_pred(δ,v_max)⊆Z 才允许按当前速度签发；否则自动降速或延长 N，拒绝人格契约的越界加速。

### 2.2 IP-61 CERT-PIPELINE-PROTOCOL（证书流水线协议 CPP）

1. **延迟契约注册与路径合成**：每链路/路径维护 δ=(max,p99,J,γ,s)，min-plus/保守合成为端到端契约；无界即 δ=∞ 并禁发跨网证书。
2. **Horizon-deadline 调度器**：按定义 48 计算最迟签发与过期时刻，维护剩余可用步，提前半窗续签，过期计划一律拒用。
3. **共形延迟上界与漂移监控**：在线维护 D^α；覆盖失效即进入保守模式（N→N_max、v→v_safe）并要求重新校准。
4. **关键级带宽分配**：safety kernel/heartbeat > geometry > semantic > persona/speculation；安全通道硬预留，不随模式收缩。
5. **顺序与一致性**：seq + 向量时钟、重复/乱序 last-writer-wins、只允许收缩合并；回放旧计划仅可安全执行、不可回写。
6. **两级证书路由**：L1 租约与 L2 漏斗分别走快/慢通道，使用规则由定义 50 统一裁决。

### 2.3 IP-62 NETWORK-IN-THE-LOOP-VALIDATOR（网络在环验证器 NLV）

1. **网络故障注入**：delay/jitter/reorder/duplicate/loss/partition（tc/netem 或 Isaac 桥），覆盖长尾与突发。
2. **延迟分布漂移与体制切换**：局域网↔公网↔弱网、带宽骤降、RTT 阶跃；验证 D^α 跟随与保守模式切换。
3. **预测误差覆盖与漏斗成员 fuzz**：统计 E_pred 的共形覆盖；对 F(k) 边界做对抗采样，专测「差一点落进漏斗」。
4. **模型失配注入**：质量/摩擦/接触/执行器延迟摄动，验证 Z 的声性与 Ω/R 的实际不变性。
5. **认证域不变式监控**：全程记录 x_t 是否离开 D；统计 fallback 交接、恢复时延与「无证窗口」。
6. **乱序/重复/回放**：构造迟到旧计划、重复计划、乱序 arrival，验证 seq 规则与只收缩合并。

## 3. 四层架构 v9

```
L1: TRI-FUSE(INT8) + IP-49 LIO → x, C_ms, B_t, L_m
    网络监控 → 延迟样本/契约 δ_e2e → 共形 D^α + 漂移检测
    延迟补偿预测 x̂_{t_a} → E_pred(δ, v_max)
L2: CTC + VLM + IP-35 仲裁 → 候选任务/计划分支（承接 v20 并行投机）
```

## 5. 本轮最大风险

**一句话**：所谓「安全与延迟解耦」只在认证域 D=Ω∪R 真正前向不变、且 tube Z 真正覆盖模型/扰动误差时成立；一旦 Ω/R 只是近似不变或 Z 低估误差，延迟本身虽不再直接致不安全，却会把系统推到 D 之外，使「延迟不变安全」退化为一次无证的急停赌博——因此 E97/E98/E102 必须设为红线，并以对抗延迟 + 模型失配双重注入验证，默认兜底是「保守认证的 Ω + 本地急停」而非乐观的漏斗。

### IP-60 DIMC：安全对象、延迟预测与漏斗证书

```
# ---------- 离线：构造延迟无关的安全对象 ----------
def build_certified_objects(f, X_safe, U, W, E_model, K):
    Z     = rpi_set(A_K, W + E_model)                 # tube，不含 δ
    Omega = control_invariant_kernel(f, X_safe, U, Z)  # 安全内核
    kappa_f = terminal_policy(Omega)                   # 本地 fallback
    R, kappa_rec = recoverable_set_and_policy(f, X_safe, U, Omega)
    return Z, Omega, kappa_f, R, kappa_rec

# ---------- 运行期：延迟补偿预测 + 三预算 + 签发 ----------
def issue_funnel_cert(x_last, pi_inflight, delta_max, Delta_t, goal,
                      Z, Omega, kappa_f, R, kappa_rec, persona):
    t_a  = monotonic_now() + delta_max
    xhat = delay_compensated_predict(x_last, pi_inflight, delta_max)  # 定义 45
    # 三预算：E_pred(δ, v_max) ⊆ Z，否则降速（人格不得越过）
    v_cap = v_delay_cap(delta_max, Z)
    v_max = min(persona_cap(persona), v_cap)
    E     = prediction_error_set(delta_max, v_max)
    if not subset(E, Z):                     # 保守模式：再降速或拉长前瞻
        v_max = reduce_speed_until(lambda v: subset(E(delta_max, v), Z))
    D_alpha = conformal_delay_bound(window_delays(), alpha)
    N = clip(ceil(D_alpha / Delta_t) + N_use, N_min, N_max)   # 定义 48/49
    prob = tube_mpc(xhat, goal, N,
                    tighten(X_safe, Z), tighten(U, K @ Z),
                    terminal=Omega, speed=v_max)
    if not prob.feasible:
        return FallbackOnly(Omega, R, kappa_f, kappa_rec, seq=next_seq())
    return FunnelCert(plan=prob.v, nominal=prob.z, funnel=prob.F,
                      Omega=Omega, R=R, kappa_f=kappa_f, kappa_rec=kappa_rec,
                      tau=monotonic_now(), t_a=t_a, N=N,
                      delta_max=delta_max, seq=next_seq())

# ---------- 使用期：重定基 + 分支降级 ----------
def use_funnel_cert(c, x_now, t_now, Delta_t):
    if c is None or network_partitioned():
        return emergency_fallback(x_now, c)
    if c.seq < last_applied_seq:              # 旧计划不回写、不抢新
        return current_action(x_now)
    k = floor((t_now - c.t_a) / Delta_t)
    if k < 0 or k > c.N:                      # 未到或 horizon 过期
        return emergency_fallback(x_now, c)
    if c.funnel.contains(k, x_now):           # 定理 47(i)：延迟不变安全
        last_applied_seq = c.seq
        return c.plan[k]
    return emergency_fallback(x_now, c)       # 定理 47(ii)(iii)(iv)

def emergency_fallback(x, c):
    if c is not None and c.R.contains(x):
        return c.kappa_rec(x)                 # 可恢复域 -> 恢复进 Ω
    if c is not None and c.Omega.contains(x):
        return c.kappa_f(x)                   # 安全内核 -> 保持
    return certified_estop(x)                 # 最后手段，设计上应被排除
```

### IP-61 CPP：延迟契约、horizon deadline、续签与关键级带宽

```
def end_to_end_contract(path):
    d = Contract(max=0, p99=0, J=0, gamma=0, sync=0)
    for e in path:
        d.max   += e.delta_max
        d.p99   += e.delta_p99
        d.J     += e.J
        d.gamma  = 1 - (1 - d.gamma) * (1 - e.gamma)
        d.sync  += e.sync               # 时钟同步误差保守累加
    if not finite(d.max): d.max = INF   # 未知即无穷，禁发跨网证书
    return d

def latest_start(c, delta_p99, Delta_t):
    return c.t_a + c.N * Delta_t - ceil(delta_p99 / Delta_t) * Delta_t

def pipeline_tick(tasks, delta_p99, Delta_t):
    for t in tasks:
        rem = remaining_steps(t.active_cert)
        if rem <= N_use(t) // 2:                    # 半窗提前续签
            if monotonic_now() > latest_start(t.active_cert, delta_p99, Delta_t):
                mark_at_risk(t); enable_fallback(t) # 来不及则先保 fallback
            else:
                enqueue_issue(t)
    # 关键级带宽：安全内核/heartbeat 硬预留，不随模式收缩
    allocate_bandwidth(tasks, order=[SAFETY, GEOMETRY, SEMANTIC, DIALOGUE])
    return edf(tasks)

def adaptive_horizon(delays, alpha, Delta_t):
    D = conformal_quantile(delays, alpha)            # 第 ⌈(n+1)(1−α)⌉ 个
    if empirical_coverage(delays, D) < 1 - alpha - eps or drift_detected(delays):
        set_conservative_mode(N=N_max, v=v_safe)      # 覆盖失效 -> 保守
        return N_max, D
    return clip(ceil(D / Delta_t) + N_min, N_min, N_max), D
```

### IP-62 NLV：网络在环与认证域不变式

```
def nlv_run(scenario):
    net   = NetworkEmulator(delay=scenario.delay, jitter=scenario.jitter,
                            loss=scenario.loss, reorder=scenario.reorder,
                            partition=scenario.partition_schedule)
    plant = SimPlant(model_error=scenario.model_error, delay_act=scenario.act_delay)

               or record_certified_gap(t)             # 认证域不变式（红线）
        plant.step(u, w=net.sample_jitter(), model_err=scenario.model_error)
    return metrics(violations, coverage=cover(E_pred, alpha),
                   fallback_rate, gaps, stale_rejects, reorder_writebacks)
```

| IP-51 两级守卫 | O(\|E\|) 比较 + O(1) 成员 | 同 L0 + 漏斗 | L1 否决 + L2 成员/fallback ⟹ 无陈旧放行 |
| IP-58 关键级调度 | O(k log k) | O(k) 预算/带宽表 | 只删不增 + 硬预留 ⟹ 切换点不变式保持 |

**核心定理复述**：
1. **延迟不变安全（定义 47）**：在 Z 声、Ω 不变、R 可恢复且 x∈D 的前提下，任意延迟下执行「计划 ∨ κ_rec ∨ κ_f」都保持 X_safe；延迟只决定走哪一支。
2. **安全/性能解耦（定义 47 推论）**：δ 只改变漏斗成员概率（可用性），不改变 Z/Ω/R 声性；因此**不存在「延迟直接把系统变成不安全」的路径**，只存在「延迟把系统逼出认证域」的路径。
3. **无饥饿（定义 48）**：N≥⌈δ_max/Δt⌉+N_use 且按时续签 ⟹ 任意时刻有可覆盖计划；分区例外由 fallback 接管。
4. **只收缩合并（定义 50）**：乱序/重复/迟到只允许让允许动作集变小，故消息顺序不能制造不安全放行。

| E98 认证域不变式 | x_t 离开 D 次数；κ_rec 恢复成功率；恢复时延；无证窗口 | 0；≥99%；<200ms；0 |
| E99 函数 vs 标量传输 | 同带宽可用 horizon 延长；本地求值延迟；证书体积 | ≥3x；<5ms；<1KB |
| E100 流水线/deadline | 过期计划拒用率；乱序回写；重定基正确率；饥饿事件 | 100%；0；100%；0 |
| E101 网络过载关键级 | 安全内核/监控/heartbeat 保活；persona/投机裁剪；恢复时延；违例 | 100%；按级裁剪；<100ms；0 起 |
| E102 长时程弱网 | 100h 不安全事件；分区/丢包/重复/重排覆盖；死锁；任务成功率 | 0 起；全故障；0；≥90% |

**对照基线**：v20 纯租约（延迟越大越收缩）、CBF-only（无前瞻）、naive latest-plan（不重定基）、oracle-delay（零延迟上界）、无 NLV 的纯仿真。

**回退**：
- E95/E98 不达标 → 关闭跨网计划，退回纯本地安全内核 + v20 租约；
- E96 不达标 → 缩短 δ（本地推理/边缘部署）或降速，禁止靠加 N 硬撑；
- E97 覆盖失效/模型失配 → 收紧 Z、降低 v_max、提高 fallback 比例直至重标定；
- E99 无收益 → 退回标量证书 + 串行本地监控；
- E100 乱序回写 → 强制单写者 + 代际令牌；
- E101 过载违例 → 硬隔离安全核与 heartbeat，冻结个性化；
- 任何红线失败 → 熔断回退 v20。

## 5. 风险与缓解（增量）

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| Z/Ω/R 只是近似不变（模型失配、接触/摩擦未建模），「延迟不变安全」静默失效 | 高 | E97/E98/E102 红线；对抗延迟 + 模型失配双注入；Z 由鲁棒可达性 + 共形双重取大；在线监控不变式并提前 fallback |
| 延迟分布漂移使 D^α 欠覆盖，计划频繁落不进漏斗，可用性崩塌 | 高 | E96 红线；漂移检测 + 保守模式（N↑、v↓）；本地推理缩短 δ；三预算降级；绝不靠放松 Z 换可用性 |
| 预测误差随 δ/v 增长越过 Z，计划大量被拒 | 中-高 | E97/E96；E_pred⊆Z 才签发；自动降速/加前瞻；人格加速请求一律受 v_delay_cap 约束 |
| horizon 太短导致计划饥饿/重规划死锁 | 中-高 | E100 红线；N≥⌈δ_max/Δt⌉+N_use；半窗续签；最迟签发检查；fallback 兜底 |
| 乱序/重复计划回写覆盖新计划，造成执行抖动 | 中 | seq + 向量时钟；旧计划可安全执行但不回写；只收缩合并；E100 专项 |
| x_t 离开认证域 D 时只剩无证急停 | 高 | 设计上以保守 R、提前 fallback、速度上限保证 x∈D；E98 监控无证窗口；急停本身需认证（受控制动） |
| 时钟同步误差 s 使 lease/horizon 时间戳失真 | 中 | 端到端契约累加 s；PTP/硬件单调时钟；s 大时禁止用乐观 horizon |
| 带宽过载时安全通道被挤占 | 中 | 关键级带宽 + 安全/ heartbeat 硬预留；HI 模式只删不增；E101 |
| 漏斗/Z 过度保守，性能退化到不如纯租约 | 中 | E99 对照；调 tube 表示（椭球/多面体）；只在 E_pred⊆Z 边界内取最小保守；但 soundness 优先 |

## 6. 本轮最大风险

**一句话**：所谓「安全与延迟解耦」只在认证域 D=Ω∪R 真正前向不变、且 tube Z 真正覆盖模型/扰动误差时成立；一旦 Ω/R 只是近似不变或 Z 低估误差，延迟本身虽不再直接致不安全，却会把系统推到 D 之外，使「延迟不变安全」退化为一次无证的急停赌博——因此 E97/E98/E102 必须设为红线，并以对抗延迟 + 模型失配双重注入验证，默认兜底是「保守认证的 Ω + 本地急停」而非乐观的漏斗。
