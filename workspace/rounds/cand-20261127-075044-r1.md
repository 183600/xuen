## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（多语言支持 → 策略的「第一公里」是文本，不是图像）**
直觉：观测里唯一告诉策略「要做什么」的是 `observation.language`（F20），而它是自由文本。图像回答「世界长什么样」，语言回答「目标是什么」。绝大多数队伍把语言当固定常量（直接吃官方任务名），但接口没有任何机制保证评测下发的是训练时见过的模板：可能是中文、可能是改写、可能带物体属性描述。一旦指令语义接地失败，动作仍合法、时延仍正常、日志全绿——但机器人在做另一件事，32 个任务同时静默失败。这是典型的**全局乘性风险**：不是某个轴掉点，而是整条链路的前提错了。多语言支持的正确打开方式不是「让模型学会所有语言」，而是**在模型前加一层确定性的指令规范化/别名解析**，把任意表述映射到训练分布内的规范任务 id 与结构化提示；再用多语/改写增广把训练侧的指令分布撑宽。核心反直觉点：**在一个只靠文本给任务的接口里，最便宜、最高杠杆的鲁棒性改造在文本侧，不在视觉侧。**

**灵感 2（通信延迟 → 控制回路的「隐形延迟」是被记录在案的可信度信号）**
直觉：README §6 白纸黑字写着会记录每步时延及其波动，并可能与成绩一同展示（F21）。这意味着延迟不只是「任务成功就无所谓」的工程细节，而是**会被看见、被用于可信度评估**的一等指标。控制论层面更硬：网络往返 L 是反馈回路里的纯延迟，T_a 个动作又是开环执行（F23），所以第 k 个动作的信息年龄是 `L + k·dt`。L 越大反馈相位裕度越差；L 抖动越大，chunk 边界越容易出现动作跳变，而动作统计规律性也在被监控（F21）。同时 T_a 在握手时固定，意味着第 2 轮 I4 的「自适应 chunk 长度」在接口上**不可直接实现**——只能改为「固定 T_a、自适应有效前缀 + 安全尾段」。核心反直觉点：**chunk 不是越长越好也不是越短越好；T_a 是延迟冲击的吸收器，也是反应延迟的下限；真正的自由度在「chunk 内容怎么排」，不在「chunk 多长」。**

**两者统一**：多语言支持与通信延迟看似无关，实则是同一类问题——**信号在接口上的失真**：一个是语义失真（文本→任务），一个是时间失真（观测→动作）。模型能力（I1/I2）决定上限，接口保真决定这个上限能不能兑现。本轮结论：**主押注仍是数据引擎；新增的是一条「接口保真层」——把语义与时间两种失真各自用确定性组件兜住，成本低、可独立验证、不碰单模型边界。**

## 2. 对第 2 轮痛点的增量修订

- **新增 P9（指令分布未知/静默错配）**：语言字段为自由文本，评测语种与模板未公开（F20）；错配是静默的（动作合法但不达意），影响全部 32 任务。风险：概率未知、后果全局。
- **新增 P10（时延与抖动被记录且 T_a 固定）**：每步时延及波动会被记录并可能用于可信度（F21）；T_a 固定使自适应 chunk 不可直接实现（F23）；N 端口共享后端有并发/排队风险（F22）。
- P5（时间压力）补充：时延/抖动会以「慢且不稳」的形式直接吃掉可信度，不只是任务内墙钟时间。
- P6（部署）细化：从「低延迟」升级为「低且稳的延迟 + 并发隔离 + 有界最坏时延」。
- P7（先手窗口）补充：接口层是多数队伍不会碰的确定性增益区，先手成本更低。
- **I4 事实修正**：第 2 轮的「自适应 chunk 长度」在 F23 下不成立，改为「固定 T_a + 有效前缀/安全尾段」。

## 3. 研究问题（本轮立项 Q9–Q10，Q1–Q8 保留）

- **Q9（指令规范化的最小充分性）**：在未知语种/改写分布下，用什么表示（规范任务 id / 结构化槽位 / 多语嵌入最近邻）与什么置信门控，能把指令接地错误率压到可接受，同时不伤标称英文模板？
- **Q10（固定 T_a 下的时限最优动作整形）**：给定网络时延 L 及其抖动，如何选全局 T_a、如何在一个 chunk 内划分「有效前缀 / 安全尾段」、如何在超时前回退到当前观测的保持动作，使任务成功率与 p99 时延稳定性同时最优？

## 4. 设计原则（新增 PR6，其余保留）

- **PR6 接口保真优先律**：任何「模型侧增益」都隐含假设语义与时间两条信号不失真；先用确定性组件把这两条兜住（可离线验证、零权重更新），再谈模型侧增益。与 PR1（计分轴）、PR5（数据杠杆）互补：PR1 决定做什么，PR5 决定怎么喂，PR6 决定信号能不能到。
- PR1–PR5 保留（第 1、2 轮）。

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2 · 接口保真层）

> 检索日期：2026-11-26（第 1 轮）、2026-11-27（第 2 轮）、2026-11-27（本轮）。承接 v1.1：I1/I2/I3/I5/I7 维持，I4/I6/I9 深化，I10/I11 新增，I8 扩充实验协议。清单只增改不重置。来源见 §5。

**本轮定位**：主押注不变（I2×I1 数据引擎）。I10/I11 是**接口保真保险**，专门防两类「静默归零」：语义失真（指令语种/改写导致做错任务）与时间失真（时延抖动导致可信度受损/超时）。两者都零权重更新、可离线验证，不与「单模型」边界冲突。

## 0. 创新点清单

### I10 指令规范化与多语鲁棒层（新） ★★★

- **动机**（P9/F20）：`observation.language` 是自由文本，评测真实分布未公开；若训练用英文任务名而评测下发中文/改写，指令接地失败会同时打击全部 32 任务，且完全静默（动作仍合法）。
- **与现有方案差异**：多数队伍把语言当常量；本点在模型前加一层**可审计的确定性规范化**，并在训练侧撑宽指令分布。不改变基座 VLM，不引入在线学习。
- **两部分**：
  1. **推理期规范器（零权重更新，reset 期一次）**：把原始字符串 `x` 映射到规范任务 id（或明确拒识 ⊥）。三级级联：
     - (a) 别名/词典精确命中：32 个任务的中英文名、缩写、常见同义改写（手工 + LLM 初筛）；
     - (b) 多语文本嵌入最近邻：`f(x)` 与 32 张任务卡嵌入比较，取 top-1/top-2 相似度与间隔做门控；
     - (c) 低置信时用开放词汇检测的视觉证据消歧，或退回「任务家族通用提示」而不是硬猜。
     - 门控规则：`若 sim1 < τ0 或 (sim1 − sim2) < τmargin → ⊥`，保证「拒识」优先于「错认」。
  2. **训练期指令增广（挂在 I2 loader）**：对每条 eps 的指令做离线翻译/改写，生成 K 条变体，以低概率（如 20%）替换原指令；规范模板仍占主导，确保标称英文不退化。可选：把颜色/形状/材质等属性写进描述，为「未见物品轴」提供语言侧线索（次要收益）。
- **技术可行性**：高。规范器在 CPU/单卡毫秒级；任务卡索引仅 32 项；翻译/改写全离线。reset 期完成并缓存，episode 内零额外开销（F25：reset 每 episode 一次且本就是一次网络往返）。
- **所需资源**：1 GPU 日（嵌入/翻译）+ 1 人周工程；训练增广的额外存储可忽略。
- **落地步骤**：①抓取任务卡/手册文本，建 32 任务别名表；②构建留出集（每任务 ~10 条中英改写，**不参与训练**）；③实现规范器 + 门控 + 拒识回退；④把改写增广接入 I2 loader；⑤跑 L0-L（见 §2）；⑥单任务通道中文改写抽测。
- **风险**：规范器错映射（缓解：拒识门控 + 视觉消歧 + 留出集测 accepted-risk）；若评测语言固定英文，ROI 低（缓解：只留规范器保险，砍训练增广）；同一文本对应多任务（缓解：优先用视觉/任务卡消歧）。

### I11 时限感知动作整形与延迟治理（新） ★★★★

- **动机**（P10/F21/F22/F23/F25）：时延及其波动被官方记录并可能用于可信度；T_a 握手固定，不能按调用改长；N 端口共享后端有排队风险；obs 无时间戳，只能服务端估计。
- **与现有方案差异**：常见做法是固定 T_a、每次返回完整 chunk，把 p99 暴露给模型/GC/网络抖动，且 chunk 尾部长期开环。本点在**不改 T_a** 的前提下改三件事：chunk 内容（有效前缀/安全尾段）、返回时机（有界时延回退）、全局 T_a 标定。
- **三部分**：
  1. **全局 T_a 标定**（握手前一次性决策）：用 §1.1 的延迟税/信息年龄约束做可行性筛选，再用 L0-Ta 网格在代理成功率与 p99 稳定性上选 Pareto 点。官方示例 T_a=8 只作起点，不作结论。
  2. **有效前缀 + 安全尾段**：设有效前缀长度 `p ≤ T_a`。动作 `0..p−1` 由模型给出；`p..T_a−1` 由安全尾段填充（保持当前观测位姿/关节、速度归零、夹爪不变；接触任务用「轻保持」而非回撤）。`p` 由时延治理器在线调整：时延/抖动升高 → 缩短有效前缀，把更多步交给安全尾段，限制开环风险。
  3. **有界时延回退**：给模型推理设软截止时间；超时则以**当前观测**构造保持动作 chunk（<1ms，无需模型）返回，避免把 p99 拖长。宁可偶发「旧而稳」，不返回「新而晚」。
  4. **chunk 边界连续性**：记录上一 chunk 最后被执行的动作，新 chunk 首步与它做短程混合/限速，避免跳变触发「动作异常值」监控（F21）。
- **时延治理器（无时间戳估计）**：设请求到达时刻 `A_i`、服务耗时 `S_i`、chunk 窗口 `W = T_a·dt`。稳定段有 `A_{i+1} − A_i ≈ W + L_i`；已知 f_c 时可反推 `L_i ≈ gap − W`，未知时只用 gap 的相对变化做 CUSUM/EWMA 抖动检测。无需客户端提供时间戳（F25）。
- **并发隔离**（F22）：若 N 端口共享一个后端，先做容量判据 `(N−1)·S << W`。例：N=3、S=40ms、T_a=8、dt≈66.7ms → W≈533ms，最坏排队 80ms ≪ W，**串行共享即可**；仅当 T_a≤2 或 S 明显变大时才需要动态批处理/模型副本。每个端口维护独立 session（reset、上一 chunk、检索先验），模型本身对 obs 无状态，隔离成本低。
- **技术可行性**：高（纯服务端；模型可在常驻 worker 推理，超时丢弃结果）。
- **所需资源**：1 人周工程 + L0 时延注入（`tc netem` 或回放时合成），无额外模型。
- **落地步骤**：①埋点记录 S_i、到达间隔、p50/p95/p99/CV；②实现治理器 + 安全尾段 + 回退；③L0-D 注入 L∈{10,40,80,150}ms 与抖动；④L0-Ta 扫 T_a∈{1,2,4,8,16}；⑤单任务通道抽测；⑥按结果决定是否与 I4 合并为一个 guard 模块。
- **风险**：回退动作过旧伤成功率（缓解：软截止设得比 p99 宽，仅兜底尖峰）；安全尾段过保守拖慢任务（缓解：L0 扫 p 函数；接触任务用轻保持）；时延仅展示不入评分 → 降级为 I6 工程子项。

## 1. 关键定义与伪代码

### 1.1 固定 T_a 的延迟模型（I11 标定依据）

记号：控制周期 `dt = 1/f_c`，chunk 长度 `T_a`，单次往返时延 `L`（含网络 + 服务 + 编解码）。

- 每个 chunk 周期：`T_a·dt + L`；**有效单步周期** = `dt + L/T_a`。
- **延迟税**：`r = L / (T_a·dt)`（相对控制周期多花的比例）。
- 第 k 个动作的**信息年龄**：`age_k = L + k·dt`（k=0..T_a−1）。
- 双重约束：延迟税 `r ≤ ε`，且最老动作年龄 `≤ τ`：
  - `T_a ≥ L/(ε·dt)`
  - `T_a ≤ (τ − L)/dt + 1`
- 可行条件：`L/(ε·dt) ≤ (τ − L)/dt + 1` ⟺ `L ≤ (τ + dt)·ε/(1+ε)`。
- 例：τ=0.3s、dt≈66.7ms、ε=0.2 → `L ≤ ~61ms`。即 **p99 往返超过约 60ms 时，不存在同时满足「低延迟税 + 低信息年龄」的 T_a**，必须降 L（裁剪观测/模型）或放宽 τ（只适用于慢任务）。
- 结论：T_a 不是拍脑袋的超参，而是由 `(L, dt, τ, ε)` 决定的可行区间与 Pareto 选择；官方示例 T_a=8 在高延迟/接触任务下可能信息年龄过大。

### 1.2 有效前缀 / 安全尾段（I4+I11 共用）

```python
def shape_chunk(policy_chunk, obs, Ta, p, contact=False):
    # p ∈ [1, Ta]：有效前缀长度；其余为安全尾段
    hold = current_hold(obs, contact)        # ee: 保持当前位姿+零速；joint: 保持当前关节；接触: 轻保持
    out = policy_chunk[:p].copy()
    out[p:] = hold[None, :].repeat(Ta - p, axis=0)   # 尾部不再外推模型动作
    out[0] = blend(out[0], last_executed_action(obs), alpha=0.3)  # 边界连续性
    return rate_limit(out)

def active_prefix(L_hat, Ta, dt, tau):       # 信息年龄约束反解
    p = int((tau - L_hat) / dt) + 1
    return max(1, min(Ta, p))
```

### 1.3 有界时延回退 + 无时间戳时延估计（I11）

```python
class DeadlineAwarePolicy:
    def __init__(self, model, Ta, soft_ms, dt):
        self.model, self.Ta, self.soft_ms, self.dt = model, Ta, soft_ms, dt
        self.prev_gap = None
        self.L_hat = None
        self.last_chunk = None

    def note_arrival(self, gap):
        # 无 obs 时间戳（F25）：用请求间隔变化估计时延/抖动
        if self.prev_gap is not None:
            W = self.Ta * self.dt
            raw = gap - W                         # ≈ L（需已知 f_c）
            self.L_hat = raw if self.L_hat is None else 0.8 * self.L_hat + 0.2 * raw
        self.prev_gap = gap

    def get_action(self, obs, gap):
        self.note_arrival(gap)
        p = active_prefix(self.L_hat or 0.0, self.Ta, self.dt, tau=0.30)
        fut = submit_async(self.model.infer, obs)          # 常驻 worker
        try:
            chunk = fut.result(timeout=self.soft_ms / 1000)
            chunk = shape_chunk(chunk, obs, self.Ta, p, contact=is_contact(obs))
        except TimeoutError:
            chunk = current_hold_chunk(obs, self.Ta)        # <1ms，宁旧勿晚
        self.last_chunk = chunk
        return self.guard(chunk, obs)
```

> 注：真实实现里用常驻推理线程 + 槽位；超时的结果直接丢弃，避免线程堆积。`tau`、`soft_ms`、`ε` 由 L0-D 标定。

def canonicalize(x: str, embed, task_cards, alias, tau0=0.75, tau_margin=0.05):
    if x.strip().lower() in alias:                 # (a) 精确别名表
        return alias[x.strip().lower()]
    v = embed(x)
    sims = [(c, cosine(v, embed(card))) for c, card in task_cards]
    sims.sort(key=lambda t: -t[1])
    (c1, s1), (c2, s2) = sims[0], sims[1]
    if s1 < tau0 or (s1 - s2) < tau_margin:        # (b) 拒识优先于错认
        return None                                # 交给视觉消歧 / 通用提示
    return c1
