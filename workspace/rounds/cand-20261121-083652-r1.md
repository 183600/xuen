# 第 1 轮（新灵感循环第 1 轮；本轮灵感：「柔顺控制」×「容错控制」）

> **基线**：上一轮（灵感「大语言模型」×「机器人」×「智能体」）MetricVoiceGauge-NCD-HUTDH-v17（定义 657–686；引理 137–142；实验 E691–E710）。
> 本轮纪律：**柔顺是权限的有界让渡，容错是在错误模型上重证，不确定性集合必须保守覆盖**。不推倒 v17：v17 的 CLP/S2C/HCG/PSV/APS/AMC、v16 的 BTS/TRM/WBC/CSC/NCS/MCA/WCB、v15 的 SCD/DSD/DCA/EDC、v13 的 AIO/RTIC/CPD/DGC/DDL/RTCR、v12 的 USG/TGC/BAA/GAGP/UC、v11 的 HAS/HCC/HATD/HDT、v10 的 NGE/DSL/CC/CWM/CAE/NCP、v9 的 AC/MW/ID、v8 的 DA/SPR/Cal 与历轮不变式全部保留。六个新组件——CEC（柔顺包络认证器）、ETS（能量账户监督器）、FDI（故障检测与隔离）、FCR（故障条件重认证器）、CAR（控制分配重构器）、RDS（鲁棒退化监督器）——以**中立元接入 v17 计划层与 v16 行为层之间**，失效即严格退回 v17（引理 143），再沿 v17→v16→v15→…→v6 退化。本轮只做三件事：把“接触作业”改写为**带能量账户的柔顺契约**、把“故障降级”改写为**故障条件下的证书重推导**、把两者统一为**不确定性集合 U 上的鲁棒证书**。

## 0. 直觉与动机

**灵感 1（柔顺控制 → 柔顺不是“更软的增益”，而是“权限的有界让渡”）**
直觉：位置控制断言“状态必须在这里”；柔顺控制故意“让步”，让环境在某个包络内推动机器人。传统阻抗/导纳控制只调增益、调阻尼，但**没有任何一层能回答“我让出了多少权限、环境最多能把它推到哪里”**。v17 的全部证书（NC、SC、PC）都建立在“状态必然落在 Post 内”之上；柔顺直接打破这个前提——环境成了未被建模的输入。核心创新：**柔顺包络认证器（Compliance Envelope Certifier, CEC）+ 能量账户监督器（Energy Tank Supervisor, ETS）**。每个节点携带柔顺契约 `CC_n=(α_n(·), F_max, E_tank, Post_n)`：`α_n(t)∈[0,1]^k` 是逐自由度**权限调度**（α=1 刚性位置，α=0 零力自由），`F_max` 与 `E_tank` 是允许的环境力上界与能量预算，`Post_n` 是必须不变的后置集。用无源性/能量账户论证：环境注入的能量填进账户；账户见底则**回收权限**（α→1，变硬）。关键反直觉点：**柔顺不是放弃安全，而是把“位置权限”兑换成“有界能量账户”；安全集一点没扩大，扩大的只是“允许环境推我多少”的预算**，故 `Exec_v18 ⊆ Exec_v17` 依然成立。

**灵感 2（容错控制 → 容错不是“少做一点”，而是“在错误的模型上重新证明”）**
直觉：v8–v17 的每张证书都是对**标称被控对象 P₀** 证明的。故障意味着真实对象 `P_f ≠ P₀`。此时证书**语法上仍然成立、语义上已经失效**——它证明的是错误系统的安全性。现有退化链只降“能力”（里程碑/阶层），却**从不重算“模型有效性”**，这是被长期忽视的根本缺口。核心创新：**故障检测与隔离（FDI）+ 故障条件重认证器（FCR）+ 控制分配重构器（CAR）**。FDI 输出**集合值**故障假设 `F̂`（对真故障的保守覆盖，而非点估计）；FCR 对每个 `f∈F̂` 重新推导 `NC_n|f`，鲁棒证书取交集 `NC^rob_n=∩_{f∈F̂}NC_n|f`；CAR 在**剩余可控自由度**内重新分配力矩。关键反直觉点：**容错的第一性问题不是“降级阶梯”，而是“检测延迟窗口”——从故障发生到被隔离之间，证书最像真的、却最危险；所以证书必须自带“可检测性余量”，覆盖 `T_detect` 内最坏漂移**。

**灵感 3（统一 → 柔顺与容错是同一件事：证书对“非标称对象”的鲁棒性）**
直觉：柔顺 = 外部有未建模的**力输入**；容错 = 内部有未建模的**参数/执行器变化**。二者都在说：“真实的被控对象不是证书假定的那个。” 统一为**不确定性集合 `U = U_ext ∪ U_fault`**：证书从 `NC_n` 升级为 `NC_n(U)`，在 U 上取最坏情况。核心不变量：**鲁棒性对 U 单调不增**，`U₁⊆U₂ ⇒ Exec_v18(U₂)⊆Exec_v18(U₁)⊆Exec_v17`。并给出一个诚实的**负结果**：柔顺能保证“力/状态安全”，但**不能保证“目标完整性”**——在安全集内，环境可以把机器人“驱赶”到任意安全但有害的构型（撞到人但力很小）。这是 v17 提示注入的物理对偶：注入攻击语言层，驱赶攻击物理层；安全率不降，但任务被劫持。

**三者如何统一**
统一为 **v17 计划层与 v16 行为层之间的鲁棒证书层**：v17 回答“哪些语言计划可被编译与调度”（`Exec_v17`），v18 回答“在外部力扰动 U_ext 与内部故障 U_fault 下，哪些节点/缝/计划仍被证书覆盖”（`Exec_v18(U)`）。CEC/ETS 处理 U_ext（柔顺侧），FDI/FCR/CAR 处理 U_fault（容错侧），RDS 把 U 的大小映射到退化阶梯（调度侧）。共享状态 `ζ_rb=(U, F̂, e_tank, α, CR, NC^rob, mode_rb)`。**CEC 回答“让出多少权限仍安全”，ETS 回答“能量账户还剩多少”，FDI 回答“可能是哪些故障”，FCR 回答“每个故障假设下证书还成立吗”，CAR 回答“剩余自由度怎么分配”，RDS 回答“U 这么大该退到哪一级”**。六者是“柔顺契约—能量监督—故障隔离—重认证—重构—退化”的实现链。

## 1. 研究问题（轮次升级版）

- **Q1（柔顺契约的可证性）**：如何由 `(F_max, E_tank)` 构造权限调度 `α_n(·)` 使 `Post_n` 在全部 `F∈U_ext` 下不变？能量账户该记“注入能量”还是“净功率积分”？账户见底时“回收权限”会不会引入抖振/硬切换冲击？
- **Q2（故障假设的集合值覆盖）**：FDI 如何输出对真故障的保守覆盖 `F̂`（含检测延迟内的未检出故障）？点估计换成集合估计后，隔离歧义如何不塌缩活性？复合故障（多执行器 + 传感器）的故障代数是否封闭？
- **Q3（鲁棒证书的交集与活性）**：`NC^rob_n=∩_{f∈F̂}NC_n|f` 在高维故障集下体积塌缩怎么办？交集为空时是“整节点不可用”还是“降到更低阶层 `h*(f)`”？鲁棒证书如何与前缀截断、缝证书复合？
- **Q4（柔顺—容错—语言三层复合）**：v17 的语言计划在柔顺下如何保证“接触任务缝”仍被覆盖？被驱赶（herding）时如何检测并触发重规划？`U` 被低估（未知未知）时有没有可观测的告警？

## 2. 设计原则（在 P28–P30 基础上新增 P31–P33）

**P31 柔顺即权限让渡律（Compliance as Bounded Authority Surrender）**
柔顺不得扩大任何 `Post`：`CC_n` 只把“位置权限 α”兑换成“有界能量账户 E_tank”，证书要求 `∀F∈U_ext` 下 `Post_n` 不变。能量账户必须非负；`e ≤ e_low` 时必须回收权限（α→1），且回收路径本身须是已认证的刚性子节点。**柔顺可执行集基数相对 v17 不增**。

**P32 故障下重推导而非复用律（Re-derive, Never Reuse, Under Fault）**
任何证书不得跨故障假设复用。鲁棒证书 `NC^rob_n(U)=∩_{f∈F̂}NC_n|f`；`F̂` 为空视为最大不确定性（不得当作“无故障”）。未检出故障窗口 `T_detect` 必须由**可检测性余量**覆盖：证书余量 ≥ `drift_bound(f,T_detect)`。交集为空 ⇒ 降至更低阶层或回退，**不得放宽交集**。

**P33 不确定性集合保守覆盖律（Uncertainty Set as Conservative Cover）**
`U` 必须是对真实扰动/故障的**过近似**：`U_ext` 覆盖所有允许的接触力/能量，`U_fault` 覆盖 `F̂` 与检测延迟内的未检出故障及其复合闭包。任何“缩小 U 以提升活性”的操作都必须有独立证据，否则禁止。**歧义只能解释为更多不确定性，绝不能解释为更少**。

## 3. 与基线的接口（如何退化）

- CEC 失效（无力/能量模型）⇒ 全节点 α≡1（纯刚性），等价 v17；
- ETS 失效 ⇒ 令 `E_tank=0`、α≡1，等价 v17（放弃柔顺）；
- FDI 失效 ⇒ `F̂` 取最大故障集（最保守），RDS 直接降到最低安全级，必要时 v16；
- FCR 失效 ⇒ 复用标称证书但禁止接触任务（仅自由空间），等价 v17；
- CAR 失效 ⇒ 不重分配，按剩余自由度降 `h*`，等价 v16 的阶层退化；
- RDS 失效 ⇒ 阶梯退化为静态，等价 v17；
- 六者全失效 ⇒ MetricVoiceGauge-NCD-HUTDH-v17，再沿 v17→v16→…→v6 退化；
- **安全继承**：CEC 只兑换不扩权、ETS 只回收不授权、FDI 只增假设、FCR 只取交不并、CAR 只在剩余自由度内分配、RDS 只降不升；`Exec_v18(U)⊆Exec_v17` 由引理 143–144 保证。

## 4. 预期贡献

1. **柔顺契约证书化**：首次把“阻抗/导纳调参”改写为“权限调度 + 能量账户”的契约，证明柔顺不扩安全集、只兑换能量预算；
2. **故障条件重认证**：指出“证书对错误模型仍语法有效”的缺口，给出集合值 FDI + 逐假设重推导 + 交集鲁棒证书；
3. **可检测性余量**：把检测延迟窗口纳入证书，证明 `T_detect` 内安全性由余量而非隔离保证；
4. **统一不确定性集合 U**：柔顺与容错统一为“证书对非标称对象的鲁棒性”，给出单调性 `U₁⊆U₂⇒Exec(U₂)⊆Exec(U₁)`；
5. **鲁棒缝证书**：把 v17 的 `SC_i` 扩展为 `SC_i(U)`，使接触任务缝在扰动/故障下仍被覆盖；
6. **柔顺—驱赶负结果**：证明柔顺保“力安全”不保“目标完整”，给出物理层 herding 的检测边界；E711–E730 覆盖柔顺、能量、FDI、重认证、重构、复合故障、端到端与消融。

## 5. 本轮最大风险

**一句话**：整套 v18 只对“我们写下来的 U”成立——若真实接触力/能量或真实故障（尤其复合故障与未检出故障）落在 `U` 之外，鲁棒证书仍是“对错误不确定性集合正确”的证书；更隐蔽的是，柔顺把“不安全”降格为“被驱赶”，而安全集本身可能包含“力很小但位置有害”的构型（撞人、越界、进入不可逆接触），即**两张各自可靠的证书（力安全 + 模型鲁棒）复合出绝对安全却目标被劫持的结果**。

# IP-415 Compliance Envelope Certifier：柔顺契约 = 权限调度 + 能量账户
class ComplianceEnvelopeCertifier:
    def __init__(self, k_min, k_max, solver):
        self.k_min, self.k_max = k_min, k_max
        self.solver = solver                     # reachability / energy-bound solver

    def certify(self, node, post, f_max, e_tank):
        # 反解：求 alpha(t) 使 max_{F in U_ext} reach(alpha,F) ⊆ post
        # 且对全部能量 <= e_tank 的 F 有 e(t) >= 0
        cc = self.solver.synthesize(
            pre=node.Pre, post=post,
            force_bound=f_max, energy_budget=e_tank,
            alpha_range=(0.0, 1.0))
        if cc is None or not self.energy_sound(cc, e_tank):
            return None                          # ⊥：无法在预算内保证 Post
        return cc                                # (alpha(.), f_max, e_tank, post)

    def energy_sound(self, cc, e_tank):
        # 无源性/能量账户：注入能量 - 耗散 <= e_tank 恒成立
        return max_injected_energy(cc) <= e_tank

    def robust_reach(self, node, alpha, f_max, e_budget):
        # 力有界 + 能量有界下的可达集过近似（区间/能量壳）
        return energy_reach_enclosure(node.Pre, alpha, f_max, e_budget)

class EnergyTankSupervisor:
    def __init__(self, e_tank, e_low, alpha_stiff=1.0):
        self.e_tank, self.e_low = e_tank, e_low
        self.alpha_stiff = alpha_stiff

    def step(self, e, power_in, power_out, dt):
        e = e + (power_in - power_out) * dt
        return min(self.e_tank, max(0.0, e))     # 恒非负（钳制）

    def authority(self, e):
        if e <= self.e_low:
            return self.alpha_stiff              # 账户见底：回收为刚性
        # 账户越满越软；越空越硬，连续、无抖振
        s = (e - self.e_low) / (self.e_tank - self.e_low)
        return clamp(1.0 - s, 0.0, 1.0)

    def guard(self, node, e, alpha):
        if e <= self.e_low and not is_certified_stiff(node):
            return 'RECLAIM'                     # 强制切到已认证刚性子节点
        return 'OK'


# IP-417 Fault Detection & Isolation：集合值假设，绝不点估计
class FaultDetectorIsolator:
    def __init__(self, fault_space, model, t_detect, delta):
        self.F = fault_space
        self.model = model
        self.t_detect, self.delta = t_detect, delta

    def update(self, u, y, x_hat):
        r = y - self.model.predict(x_hat, u)
        # 只保留与残差界一致的假设；宁可多留，不可少留
        F_hat = {f for f in self.F if self.consistent(f, r)}
        if not F_hat:
            F_hat = set(self.F)                  # 空集 ⇒ 最大不确定性（P32/P33）
        return F_hat, r

    def consistent(self, f, r):
        return residual_bound(self.model, f) >= norm(r)

    def drift_bound(self, f, horizon):
        # 检测延迟窗口内的最坏状态漂移上界（用于可检测性余量）
        return self.model.worst_case_drift(f, horizon)

    def detectability_margin(self, F_hat):
        return max(self.drift_bound(f, self.t_detect) for f in F_hat)


# IP-418 Fault-Conditioned Re-certifier：逐假设重推导，交集为鲁棒证书
class FaultConditionedReCertifier:
    def __init__(self, cec, plant_family):
        self.cec = cec
        self.plants = plant_family

    def recert(self, node, F_hat, u_ext):
        certs = []
        for f in F_hat:
            nc_f = derive_certificate(node, self.plants[f])   # 在 P_f 下重算 Pre/Run/Post
            if nc_f is None:
                return None                                    # 某假设下不可证 ⇒ 鲁棒不可证
            cc_f = self.cec.certify(node, nc_f.Post, u_ext.F_max, u_ext.E_tank)
            if cc_f is None:
                return None
            certs.append((nc_f, cc_f))
        return intersect_certificates(certs)                   # Post^rob=∩Post_f, CC^rob=∩CC_f


# IP-419 Control Allocation Reconfigurator：剩余自由度内再分配
class ControlAllocationReconfigurator:
    def __init__(self, alloc_matrix, tau_limits, validity_radius):
        self.B, self.lim = alloc_matrix, tau_limits
        self.validity = validity_radius

    def residual_dof(self, f):
        cols = effective_columns(self.B, f)     # 故障后仍可驱动的列
        return cols if rank(cols) > 0 else None

    def reconfigure(self, f, tau_task):
        cols = self.residual_dof(f)
        if cols is None:
            return None                          # 无剩余可控性 ⇒ 降 h*
        tau = weighted_pinv(cols) @ tau_task
        if not within(tau, self.lim) or not within_validity(cols, self.validity):
            return None                          # 超出证书有效性半径 ⇒ 不重构
        return tau


# IP-420 Robust Degradation Supervisor：U 越大越退，只降不升
class RobustDegradationSupervisor:
    RUNG = ['R0_ROBUST_FULL', 'R1_COMPLIANT_ONLY',
            'R2_FREESPACE_ONLY', 'R3_V17', 'R4_V16_DEFAULT']

    def level(self, U, F_hat, e_tank):

## 2. 推导

**引理 143（柔顺包含性：柔顺只兑换能量，不扩安全集）** 设 `CC_n` 保证对一切 `F∈U_ext`（`‖F‖≤F_max`、注入能量 ≤`E_tank`）有 `Post_n` 不变，能量账户恒非负，且 `e≤e_low` 时回收为已认证刚性子节点，则柔顺执行全程状态落在某认证 `Post` 内，且 `Exec_v18(U_ext)⊆Exec_v17`。证明：能量账户由钳制与非负更新恒非负；无源性/能量界给出注入能量的上包络，`CEC.certify` 的可达集过近似覆盖全部 `F∈U_ext`，故 `Post_n` 不变；账户见底时 `α→1` 退化为 v17 已认证刚性节点，其 `Post` 已被 v17 证明。柔顺模式与刚性模式的并仍是已认证 `Post` 的子集，未新增任何节点或放宽阈值。∎ 推论：**柔顺失效模式只有“变硬/降活性”，不会“变危险”**。

**引理 144（鲁棒证书的单调性）** 若 `NC^rob_n(U)=∩_{f∈F̂}NC_n|f` 且 `U` 越大交集越小，则 `U₁⊆U₂ ⇒ Exec_v18(U₂)⊆Exec_v18(U₁)⊆Exec_v17`。证明：对每个 `f`，`NC_n|f` 是 `P_f` 下的认证集；交集对假设集单调不增；CEC 对 `U_ext` 同样取最坏情况，`U_ext` 增大则可达集过近似增大、可证节点减少；CAR 只在剩余自由度内分配、RDS 只降不升，均不新增授权。故 U 增大只移除可执行项。∎ 推论：**把“未知”误当成“已知无故障”（缩小 U）会系统性高估 `Exec_v18`——这正是 P33 禁止的**。

**引理 145（检测延迟窗口的可检测性余量）** 设真故障 `f*`（幅度 ≥δ）在 `t₀` 发生，FDI 在 `T_detect` 内以概率 ≥1−β 检出，且每张执行证书的余量 ≥ `drift_bound(f*,T_detect)`，则在 `[t₀,t₀+T_detect]` 内证书不被违反的概率 ≥1−β。证明：故障未检出期间，`f*` 被计入 `U_fault` 的保守覆盖（P33），证书按最坏漂移预留余量；`Post` 在漂移界内不变，故即使隔离尚未完成，状态仍在证书内；检出后 FCR 重认证接管。∎ 推论：**容错的安全性在检测窗口内由“余量”而非“隔离”保证；缩短 `T_detect` 与加大余量是同一预算的两种花法**。

**引理 146（鲁棒缝覆盖）** 设 `SC_i(U)=Post_{n_i}(U)∩Pre_{n_{i+1}}(U)`，接受时对 `U` 预验非空且 `vol≥margin`，运行时逐缝复验 `x∈SC_i(U)`，则接触任务缝在扰动/故障下仍被覆盖；复验失败退前一节点 `Fallback`（继承引理 139）。证明：`Post(U)`、`Pre(U)` 均为最坏情况集，其交仍覆盖全部 `u∈U` 的过缝状态；复验失败即 `x∉SC_i(U)`，`n_{i+1}` 不运行，退至 `Fallback_{n_i}⊆Pre_{n_i}`。前缀截断只保留头部，合取对前缀封闭。∎

**引理 147（重构不扩权）** CAR 只在 `CR(f)` 的列空间内分配且限制在 `τ_lim` 与证书有效性半径内；不可行返回 ⊥ 并降 `h*`。故 `Exec` 不增。证明：分配映射的值域含于剩余执行器可达集，未新增自由度；超出有效性半径即拒绝；降 `h*` 只减少可达行为。∎ 推论：**重构是“在更小的盒子里重新分力”，不是“造出新能力”**。

**引理 148（柔顺—驱赶负结果：力安全 ≠ 目标完整）** 在 `U_ext` 下，存在满足 `‖F‖≤F_max` 且能量 ≤`E_tank` 的力轨迹，把状态从任意 `x₀∈Pre` 驱动到安全集 `Post` 内任意 `x₁`；同时全部证书保持成立。故柔顺不能保证目标完整性，只能保证力/状态安全。证明（构造性）：柔顺模式下 `α<1`，闭环对力输入可控；安全集连通时，沿能量预算允许的测地线施力即可在账户耗尽前到达 `x₁`；每步 `Post` 不变由引理 143 保证。若机器人始终 `α=1` 抵抗，则账户不消耗但失去接触任务能力。∎ 推论：**柔顺存在二难——要么让步（可被驱赶到安全但有害构型），要么抵抗（丧失接触作业）**；这正是 v17 提示注入的物理对偶，也是本轮最大风险的形式化来源。

**引理 149（复合故障的覆盖缺口）** 若 `F̂` 只覆盖单故障而真实故障为 `(f₁,f₂)`，则 `NC^rob_n=∩_{f∈F̂}NC_n|f` 可能不覆盖 `P_{(f₁,f₂)}`，鲁棒证书不成立。证明：`P_{(f₁,f₂)}` 的状态约束一般严格强于任一单故障模型，交集对单故障成立不蕴含对复合故障成立；除非 `F_compound=closure(F̂)` 已含复合项。∎ 推论：**故障空间必须在复合下封闭（P33 的 `F_compound`），否则“逐故障都对”的证书会在复合故障处同时失效**。

## 6. 已知风险与失效模式

1. **U 低估（未知未知）**：真实力/故障落在 `U` 之外，鲁棒证书“对错误集合正确”。缓解：在线扩 U、残差触发的 U 自适应、保守先验、异常即升 U。
2. **能量账户建模误差**：忽略动能回收/耗散非线性，账户提前或滞后见底。缓解：能量观测器、实测标定、账户留安全下限。
3. **权限回收抖振**：账户在阈值附近反复切换 α，引发硬切换冲击。缓解：α 连续插值、滞环、回收过渡节点。
4. **FDI 隔离歧义塌缩活性**：`|F̂|` 大导致鲁棒交集过小、长期退化。缓解：故障族分层、共享证书、主动激励缩短歧义。
5. **复合故障未闭合**：只覆盖单故障，复合故障处证书同时失效（引理 149）。缓解：故障代数闭包、组合枚举、组合测试。
6. **检测延迟窗口余量不足**：故障漂移快于 `T_detect` 余量。缓解：缩短窗口、加大余量、双通道 FDI。
7. **重构超出有效性半径**：剩余执行器分配虽可行但把对象推出证书模型有效域。缓解：有效性半径硬约束、模型在线辨识。
8. **鲁棒交集体积塌缩**：高维故障集下 `∩Post_f` 近空，系统退化为 v16。缓解：任务子空间投影、分层证书、活性监视。
9. **柔顺驱赶（herding）**：安全集内被推到安全但有害构型（引理 148）。缓解：接触意图检测、目标完整性监视、危险构型黑名单。
10. **安全集定义不当**：`Post` 只编码力/状态，不编码“是否撞人/是否越界”。缓解：安全谓词扩维（位置/对象/人），把目标完整性纳入证书。
11. **传感器故障与柔顺耦合**：力传感器偏置使 α 误判，账户记账错误。缓解：多源力估计、偏置可观测性、故障条件 CEC。
12. **三重证书过度保守**：NC ∩ SC(U) ∩ 鲁棒交集 ∩ 能量约束，计划通过率趋零。缓解：加权打分、证书族共享、动态 margin、活性告警。
13. **计算时延**：CEC/FCR 在计划接受时秒级求解，可能拖慢接受。缓解：离线预计算契约库、按证书族缓存、增量求解。

## 7. 本轮最大风险

**一句话**：整套 v18 只对“我们写下来的 U”成立——若真实接触力/能量或真实故障（尤其复合故障与未检出故障）落在 `U` 之外，鲁棒证书仍是“对错误不确定性集合正确”的证书；更隐蔽的是，柔顺把“不安全”降格为“被驱赶”，而安全集本身可能包含“力很小但位置有害”的构型（撞人、越界、进入不可逆接触），即**两张各自可靠的证书（力安全 + 模型鲁棒）复合出绝对安全却目标被劫持的结果**。
