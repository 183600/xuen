> **基线**：MetricVoiceGauge-NCD-HUTDH-v23 建立在 v22 + IP-431–435（HDL/ACSC/DCSC/HPC-E/CFC++）之上，其下承 v21 语义-规范层（SDC/CAC/DCL/GIC）、v20 联邦感知证书（PCA/CTS/CFC/HPC/CFCtrl）与 v19/v17（DCM/OGCC/CCV/DRS/OGC、CLP/S2C/HCG/PSV/APS/AMC）。本轮不推倒任何既有模块。
> **本轮纪律**：**语言指令是"不可信编译器"（人的意图 → 计划），机器人操作系统是"分布式不可信通道"（计划 → 跨节点动作）；二者的失败模式同构——都把不确定性静默地朝"更自由、更乐观"的方向消解。** 因此本轮不加新的"能力"，只加两条"折叠线"：在证书塔的入口把人话折成保守的解释集，在出口把证书折成可合并、可溯源的分布式状态。全部沿用同一条**保守折叠原理**，使 `Exec_v23 ⊆ Exec_v22 ⊆ … ⊆ Exec_v18` 继续成立。

## 0. 直觉与动机

**灵感 1（语言指令 → 把"点估计的意图"换成"带覆盖保证的解释集"）**
直觉：v22 之前的每一层都假设"计划 π 已经给定"，可人给的是"去厨房把杯子拿来，别吓到猫"。语言天然欠定：lexical（杯/盏/马克杯）、指代（哪个杯子）、否定辖域（"别碰 A 或 B" 是 ¬(A∨B) 还是 (¬A)∨(¬B)）、量词辖域、时序（"先…再…"）。用一个 LLM 取"最可能的解析"再交给证书塔，等于**让不可信编译器替我们做了安全决策**——它若把"别碰人或猫"误解析成"别碰人"，证书依然会为一次会碾到猫的计划盖章。核心创新：**语言指令 conformal 编译器 (LICC)** 输出的是**解释集** `Γ_NL(u)` 而非单一解析，并附 ≥1-α 的覆盖保证；执行条件是**普适安全**：`∀ I ∈ Γ_NL(u): π ∈ Safe_v22(I) ∩ CC_v22(I)`。这才是把 P34/P35 的"只加不赎、只交不并"真正推进到意图层。关键反直觉点一：**更准的 LLM 不一定更安全；安全取决于解释集的覆盖与"折叠方向"，而非点准确率——一个 95% 准确的解析器，其 5% 错误恰恰集中在最含糊、最危险、最需要保护的指令上。** 关键反直觉点二：**歧义不必都要澄清**——只有当歧义**跨越了某张证书的边界**时才值得提问（**ACC，Active Clarification under Certificate**）；对不影响证书的歧义直接按保守方向折叠执行，活性不受损。关键反直觉点三：语言还能表达**规范**（"慢一点""别进厨房""可以先让一下"），所以 LICC 的输出不是"目标"，而是**义务型意图集 (typed deontic intent)**，直接喂给 v21 的 DCL；而"拒绝执行 + 给出可审计的自然语言理由"本身就是一种合规结果，不是失败。

**灵感 2（机器人操作系统 → 证书必须随消息走，且能无序合并）**
直觉：v22 把 `ζ` 当成一个全局一致的共享状态。真实 ROS2 图里，证书由不同节点在不同时刻、经不同 QoS（reliable/best-effort、deadline、liveliness、durability）发布：消息会丢、会乱序、会重复、会重放；topic 可被 remap/namespace 改写；节点可被供应链污染；各节点时钟有偏。此时"把 200ms 前的 SAFE 当现在的 SAFE"和"丢了障碍消息就等于没有障碍"都是**朝自由方向的静默消解**。核心创新：**证书随消息 (CCM, Certificate-Carrying Message)**——每条安全相关消息带一个证书信封 `⟨payload, cert, prov, prov_root, topic_id, vclock, t_src, ttl, att⟩`；接收侧状态是**证书 CRDT (CCRDT)**：保守序 `⊑` 下的 join-半格，合并 `⊔` 满足幂等/交换/结合，故**与到达顺序无关、重复消息不涨置信、重放无效**。关键反直觉点一：**在分布式中，"丢弃过期 SAFE"是危险的，"保留过期障碍"才是保守的**——正证据（障碍）过期仍保留（它可能还在），负证据（自由/无人）过期必须**衰减为 unknown**（假设可能有人）；两者都只朝保守方向移动（**不对称过期律**）。反直觉点二：**不可信节点的正证据仍可采纳（它说"这里有东西"只会让我们更保守），但其负证据一文不值（不能据此解放空间）**——这恰是 v21 手势通道"在场翻转"、v22 模态仲裁在中间件层的推广：所有不可信的失败都折向"障碍更多、自由更少"。反直觉点三：**新鲜度不能是假设，必须是 QoS 契约**——证书的 TTL 必须由 ROS2 的 deadline/liveliness/reliable 强制背书，QoS 弱于契约即触发保守退化；时钟偏差在新鲜度不等式里是**被减去**而非加上的。

**三者如何统一（"语言→证书→中间件"是同一条保守折叠的三个落点）**
语言与中间件是同构的：都是"不可信翻译器"，都可能把不确定性朝乐观方向消解。因此本轮只引入一条算子族——**保守折叠**：解释层对 `Γ_NL` 取 `Safe` 的**交**（任一可能解释里的限制都要满足、任一许可都必须全体同意才生效，即 meet），中间件层对证书状态取保守序的 **join**（障碍取并、自由取交）。二者方向相反，但都使可达集单调收缩：`Exec_NL(u) = ⋂_{I∈Γ_NL} Safe_v22(I) ⊆ Safe_v22(I*)`，`Fused = ⊔_i Cert_i` 且 `Safe` 对 `⊑` 向下封闭（更保守仍安全）。共享状态扩展为 **`ζ_v23 = ζ_pgev ∪ (Γ_NL, CIG, 𝒞_bus, att, vclock)`**；统一准入门 **HPC-EL = (HPC-E, Γ_NL-稳健可证, CCM-有效)**：只有"几何∧规范∧负信息∧能量（HPC-E）∧ 整解释集安全（LICC）∧ 分布式证据可合并且新鲜可溯源（CCM/CCRDT）"才进入执行；任一缺失只向 v22/v21/… 保守退化。**CIG（可证意图图）** 是语言层的输出、也是中间件层的输入：它既是"子目标 DAG + 每节点证书义务"，又是"ROS2 action/QoS/attestation 的部署契约"——若 ROS 图给不出契约要求的 QoS/attestation，则该图在部署前即被判不可证（从源头拒绝，而非运行期补救）。

## 1. 研究问题（在 Q1–Q11 之上新增 Q12–Q16）

- **Q12（语言歧义的"安全相关"可证性）**：如何构造 `Γ_NL(u)` 使 `P(I* ∈ Γ_NL(u)) ≥ 1-α` 在**语言分布漂移**（新说法/方言/ASR 噪声/多语混用）下仍成立？非一致性分数 `s(I)` 该如何取，才能度量"**证书相关**的语义距离"而不是泛泛的句义距离（例如只在语气词上不同的两个解析应同分，而"别碰人"与"别碰人或猫"必须显著不同分）？`∀I∈Γ_NL` 的普适安全检查在多少候选、何种单调性下可多项式判定？
- **Q13（澄清的活性最优性）**：给定证书边界诱导的等价类划分，最小澄清策略（在期望活性损失最小意义下）是否存在贪心最优？"边际覆盖 vs 条件覆盖"的鸿沟（见 §5 风险）如何用 **Mondrian/风险分层 conformal** 与 **OOD→全集退化** 在工程上被压住？
- **Q14（分布式证书的收敛与可靠）**：在任意丢包/乱序/重复/重放/分区下，CCRDT 的 `⊔` 是否保证**最终一致且始终保守**（不产生虚假自由）？在**崩落故障**下保持健全，在**拜占庭故障**下如何靠 attestation + topic 绑定 + 正/负不对称把损害限制在"活性"而非"安全"？有界钟偏与 QoS 违约下的"陈旧保守度"如何定量刻画？
- **Q15（QoS 契约的可满足与部署判定）**：给定 CIG 的证书义务（每节点需要的 deadline/liveliness/reliable/attestation），如何判定一个具体 ROS2 图能否**放电**这些义务（部署可行性）？不可满足时如何在不越界的前提下逐级松弛目标（而非直接 SafeStop）？
- **Q16（端到端安全继承定理）**：对部署在 ROS2 上的 CIG，是否恒有 `Exec_v23 ⊆ Exec_v22`？特别地，当 LLM 编译器产出一个"**听起来合理且物理安全、但并非人所指**"的计划时，证书塔是否仍会放行（语义安全 vs 物理安全的分野），以及这构不构成安全违约？

## 2. 设计原则（在 P41–P42 基础上新增 P43–P46）

**P43 歧义保守折叠律（Conservative Ambiguity Folding）**
对任一指令 u，不取点估计解析，而取 conformal 解释集 `Γ_NL(u)`（覆盖 ≥1-α）。**限制按并集采纳，许可按交集生效**：可行计划集 `Exec_NL(u) = ⋂_{I∈Γ_NL(u)} (Safe_v22(I) ∩ CC_v22(I))`。任一可能解释里的禁止/义务都进入约束（meet 不放大自由），任一许可只有在 `Γ_NL(u)` 全体同意时才解除对应限制。**OOD/校集支撑外 ⇒ `Γ_NL(u) := 全集`（最保守）并强制澄清**，绝不点预测。澄清只在"歧义跨越证书边界"时触发（ACC）；不跨越即按上式保守折叠直接执行。故 `Exec_NL(u) ⊆ Safe_v22(I*)`，且 `Γ ⊆ Γ' ⇒ Exec_NL(Γ') ⊆ Exec_NL(Γ)`（解释集越大，执行越窄——单调保守）。

**P44 证书随消息·单调合并律（Certificate-Carrying & Monotone Merge）**
每条安全相关消息携带证书信封；接收状态是保守偏序 `⊑`（障碍更多、自由更少者为上）下的 join-半格，`⊔` 幂等/交换/结合。**合并顺序无关、重复不涨置信、重放无效**；门控只检查合并后的 LUB（`Safe` 对 `⊑` 向下封闭：更保守仍安全）。**不可信来源的正证据（报障碍）可采纳，负证据（解自由）一律不采纳**。由此 v21 的 NMS 去重、v22 的模态仲裁被提升为总线级结构性质，而非事后补丁。

**P45 新鲜度即 QoS 契约律（Freshness-as-QoS-Contract）**
证书有效期 `ttl` 必须由 ROS2 QoS（reliable/deadline/liveliness）实际背书；实际 QoS 弱于契约、或 `t_r + ε_skew − t_src > ttl` 时，证书不得保持原强度，只能**衰减为更保守投影**（绝不保持原自由）。时钟偏差在新鲜度判定中**减**去。`topic_id` 绑定实际到达的 channel（防 remap 串台）；`prov` 链须回溯到钉扎的信任根（防伪造/篡改）。契约不可满足的 CIG 在部署前判不可证。

**P46 不对称过期·不对称信任律（Asymmetric Decay & Trust）**
**正证据**（障碍）过期/来源不可信仍保留（它可能还在 ⇒ 更保守）；**负证据**（无人/自由）过期则退化为 `unknown`，来源不可信则拒收其"解自由"效力。所有失败都只朝"障碍更多、自由更少"方向移动，使任何模块崩溃都向 v22 甚至更保守退化，而不是产生虚假自由。

## 3. 与基线的接口（如何退化）

- LICC 失效（解析器/ASR 崩溃）⇒ `Γ_NL := 全集`，只接受"对任意解释都安全"的原子动作（如原地静止/让位），其余澄清或 SafeStop ⇒ 严格 ⊆ v22；
- LICC OOD/覆盖失守 ⇒ 同上，退为全集 + 强制澄清 ⇒ 保守；
- CIG 不可部署（QoS/attestation 契约无法放电）⇒ 该子目标不可证，逐级松弛或回退 v22 的静态默认 ⇒ ⊆ v22；
- CCM 信封缺失/校验失败 ⇒ 该消息按 P46 只允许"加障碍"、不允许"解自由"，等价于把分布式消息降级成 v22 的单机快照 ⇒ ⊆ v22；
- CCRDT 合并半格被破坏（实现缺陷）⇒ 退化为"逐条独立校验 + 取最保守者"（保守 join 的朴素实现）⇒ 仍 ⊆ v22；
- QoS 违约 / 钟偏超界 ⇒ 过期负证据全部 decay 为 unknown ⇒ 比 v22 更保守（活性下降）；
- 所有新模块失效 ⇒ 完全回退 v22 ⇒ `Exec_v23 ⊆ Exec_v22 ⊆ v21 ⊆ v20 ⊆ v19 ⊆ v18`（引理 162 的延续）。
- **全链保守方向**：语言层只做 meet/收缩、中间件层只做 join/保守、二者对不可信只"减自由"；因此任意失效都向更保守退化，安全继承不需要新的全局假设，只需要每条消息/每个解释都遵守 P43–P46。

## 4. 预期贡献（在 1–9 基础上延伸）

10. **解释集取代点估计**：首次把自然语言指令编译为带 conformal 覆盖保证的**解释集**，并用"全解释集普适安全"的 meet 条件替代"最可能解析"的点安全，使语义歧义成为显式可审计集合而非隐式乐观假设；
11. **保守折叠算子族**：给出"限制取并、许可取交"的语言侧 meet 与"障碍取并、自由取交"的中间件侧 join，证明二者方向相反却同向收缩可达集——语言与 ROS 被统一到同一条保守折叠原理；
12. **澄清即证书边界检测（ACC）**：只在歧义跨越证书边界时提问，并以 Mondrian/OOD→全集处理边际覆盖与条件覆盖的鸿沟，兼顾安全与活性；
13. **证书随消息 + 证书 CRDT**：把 v21/v22 的单机单调证据/NMS 去重/模态仲裁提升为总线级 join-半格，结构性封堵乱序、重复、重放与"众口铄金"，且合并顺序无关；
14. **溯源证明 + QoS-新鲜度契约 + 不对称过期/信任**：topic 绑定防 remap、attestation 防伪造、skew 保守扣减、QoS 弱即退化、过期负证据衰减为 unknown，给出分布式证书的健全性边界；
15. **意图图即部署契约 + 端到端继承**：LICC 产出的 CIG 同时是 ROS2 action/QoS/attestation 需求图，部署前做可满足性判定；证明 `Exec_v23 ⊆ Exec_v22`，并显式区分"证书齐备的物理安全"与"语义上做对了事"，把后者列为可证伪的开放问题而非已解决。

## 5. 本轮最大风险

**一句话**：语言侧的 conformal 覆盖只是**边际**保证、中间件侧的新鲜度只是**契约**保证；在最需要它们的**罕见/对抗性指令 + QoS 降级/钟偏**工况下二者可能同时失守，系统会以一条**完全合规、可审计、可溯源**的证书链执行一次"**基于过期证据、且把人的意图静默折叠错了**"的动作——即"证书齐备的错事"。

## 1. 形式化定义、引理与安全继承

**定义 926（解释集与覆盖）** 设分割 conformal 校准集给出一致性分数经验分位 `q̂ = s_{⌈(n+1)(1-α_NL)⌉}`。定义 `Γ_NL(u) = { I ∈ G(u,c) : s_I ≤ q̂ }`。在可交换性假设下有 `P(I* ∈ Γ_NL(u)) ≥ 1-α_NL`。非一致性分数取**证书相关**度量：`s(I) = d_Ob(I, I*)`，其中 `d_Ob` 只比较两解析导出的**义务签名**（禁止集、义务集、许可集、指代绑定的目标 ID），忽略不影响证书的修辞差异。

**定义 927（稳健可执行集）** `Exec_NL(u) = ⋂_{I∈Γ_NL(u)} (Safe_v22(I) ∩ CC_v22(I))`。执行条件：`Exec_NL(u) ≠ ∅`。该定义把"限制取并、许可取交"编码为对 `Safe∘CC` 的 **meet**。

**引理 928（解释集单调收缩）** 若 `Γ ⊆ Γ'`，则 `Exec_NL(Γ') ⊆ Exec_NL(Γ)`。
*证明*：对更大集合取交只会更小（交的子集）。∎
*推论*：OOD 时 `Γ := 全集` 是"最安全但最不活跃"的端点；这给出 P43 的 OOD 退化方向。

**定义 929（保守序与 join-半格）** 在证书集合上定义 `σ ⊑ σ'` 当且仅当 `Obs(σ) ⊆ Obs(σ')` 且 `Free(σ') ⊆ Free(σ)`（障碍更多、自由更少者为上）。`⊔` 为最小上界：`Obs(σ⊔σ') = Obs(σ)∪Obs(σ')`、`Free(σ⊔σ') = Free(σ)∩Free(σ')`。安全性谓词 `Safe` 对 `⊑` **向下封闭**：`Safe(σ) ∧ σ ⊑ σ' ⇒ Safe(σ')`（更保守仍安全）。

**引理 930（CRDT 收敛与抗重放）** `⊔` 幂等（`σ⊔σ=σ`）、交换、结合，故对任意到达顺序与任意重复，所有已到消息的合并结果等于其集合的 LUB，与顺序/重数无关。*证明*：半格公理直接推出；重复消息不改变 LUB。∎
*推论*：v21 的"众口铄金"（同一证据被多节点重复计票）在**值**层面被结构性消除：`SAFE ⊔ SAFE = SAFE`，不可能因重复而"更加 SAFE"。

**定义 931（不对称衰减 D）** `D(σ) = σ` 若 σ 为正证据（障碍类）；`D(σ) = UNKNOWN_MAYBE_OCCUPIED` 若 σ 为负证据（缺席/自由类）。恒有 `σ ⊑ D(σ)`。
**引理 932（衰减单调保守）** 对任意 σ，`Safe(σ) ⇒ Safe(D(σ))`。*证明*：D 只可能增加障碍或减少自由，由 929 的向下封闭性得。∎

**定义 933（CCM 准入）** 接收方 r 在 `t_r` 对消息 msg 的完整接入为：
`integrate(msg,t_r) = state ⊔ ( ∈Admit ? cert : D(cert) )`，
其中 `Admit = verify_chain(prov, prov_root) ∧ (topic_id = H(arrival_topic)) ∧ att.is_allowed() ∧ Fresh(msg,t_r)`。注意 `Admit` 失败**不丢弃**，而是衰减：正证据保留、负证据→unknown（P45/P46）。

**定理 934（端到端安全继承 `Exec_v23 ⊆ Exec_v22`）** 若 (i) P43 折叠成立、(ii) Safe 对 ⊑ 向下封闭、(iii) D 单调保守、(iv) 每条支撑消息或 Admit 或衰减，则任一被 HPC-EL 放行的计划 π 属于 `Exec_v22`。
*证明骨架*：HPC-EL 的第一个门 HPC-E 已给出 `π ∈ Exec_v22` 的能量/几何/规范证书。第二门给出 `π ∈ Safe_v22(I) ∩ CC_v22(I)` 对**所有** `I∈Γ_NL` 成立，特别对真意图 `I*`（覆盖成立时）成立。第三门把分布式证据经 `⊔`/`D` 合并为 `Fused`；由引理 932 与 929，`Fused` 至少与任何单一真实证据一样保守，故 `Safe_v22` 在 `Fused` 下成立即推出在真实状态下的 v22 证书成立。三者合取 ⇒ `π ∈ Exec_v22`。∎

**命题 935（边际 ≠ 条���覆盖；本轮的已知认识论缺口）** 分割 conformal 只保证对抽取分布的**边际**覆盖，不保证条件于"危险/罕见"分层的覆盖。工程缓解：(a) 按风险分层做 **Mondrian conformal**；(b) OOD 检测触发 `Γ:=全集`；(c) 把"条件覆盖下界"作为**需经验标定**的假设记录在证书元数据里，而非默认成立。该缺口即 §5 最大风险的形式来源。

```python
# IP-436 LICC：NL -> conformal 解释集 -> 保守折叠
class LanguageInstructionConformalCompiler:
    def __init__(self, parser_llm, calibrator, alpha_nl=0.01, ood_detector=None):
        self.parser_llm = parser_llm
        self.calib = calibrator          # split-conformal 校准器
        self.alpha = alpha_nl
        self.ood = ood_detector

    def obligations(self, I):
        # 只保留影响证书的义务签名：F/O/P + 指代绑定目标
        return (I.forbidden, I.obliged, I.permitted, I.referents)

    def score(self, I, u, c):
        # 证书相关非一致性：义务签名距离（忽略修辞差异）
        return self.calib.score(self.obligations(I), self.ground_truth_signature(u, c))

    def conformal_set(self, u, c):
        if self.ood and self.ood.is_ood(u, c):
            return ALL_INTERPRETATIONS            # P43: OOD -> 全集
        scored = self.parser_llm.candidates(u, c)
        q = self.calib.quantile(self.alpha)       # q̂_{1-α}
        return {I for I in scored if self.score(I, u, c) <= q}

    def robust_exec(self, u, c, certifier_v22):
        gamma = self.conformal_set(u, c)
        feasible = None
        for I in gamma:
            S = certifier_v22.admissible_set(I)   # Safe_v22(I) ∩ CC_v22(I)
            feasible = S if feasible is None else (feasible & S)   # meet
        if not feasible:
            return self.clarify_or_stop(u, gamma)  # ACC
        return feasible

    def clarify_or_stop(self, u, gamma):
        # 只在歧义跨越证书边界时提问
        if self.crosses_certificate_boundary(gamma):
            return ("CLARIFY", self.best_question(gamma))  # 最大信息增益/证书等价类
        return ("SAFESTOP", None)
```

```python
class CertifiedIntentGraph:
    def compile(self, I, certifier_v22):
        nodes = []
        for sg in I.subgoals:
            nodes.append(Node(
                action=sg,
                obligation=certifier_v22.obligation(sg),  # 需哪些证书
                qos=self.qos_contract(sg),                # deadline/liveliness/reliable
            ))
        return CIG(nodes=nodes, edges=I.refinement_edges)

    def deployable(self, cig, ros_graph):
        # Q15：部署可行性 = 每个节点的 QoS/attestation 义务都能被 ROS 图放电
        return all(ros_graph.can_discharge(n.qos) and ros_graph.has_attested(n.action)
                   for n in cig.nodes)
```

```python
# IP-438/439 CCM + CCRDT：证书信封 + 单调合并 + 不对称衰减
@dataclass(frozen=True)
class CertEnvelope:
    cert: Certificate
    prov: bytes            # 哈希链
    prov_root: bytes       # 钉扎信任根
    topic_id: bytes        # H(实际 topic)
    vclock: VectorClock
    t_src: float
    ttl: float
    att: Attestation

class CertificateCRDT:
    def __init__(self, skew_bound):
        self.skew = skew_bound
        self.state = bottom()            # 最不保守

    def integrate(self, msg, t_r, arrival_topic):
        trusted = (verify_chain(msg.prov, msg.prov_root)
                   and msg.topic_id == H(arrival_topic)      # 防 remap 串台
                   and msg.att.is_allowed())                 # 防伪造
        fresh = (t_r + self.skew - msg.t_src) <= msg.ttl     # 防陈旧
        if trusted and fresh:
            self.state = self.state ⊔ msg.cert
        else:
            self.state = self.state ⊔ D(msg.cert)            # P45/P46：衰减而不丢弃
        return self.state

    def fused(self):
        return self.state

def D(cert):
    if cert.is_positive():              # 障碍类：过期/不可信仍保留
        return cert
    return UNKNOWN_MAYBE_OCCUPIED       # 负证据：过期/不可信 -> unknown（保守）
```

```python
@dataclass
class HPCLR:
    hpc_e: HPCE
    licc: LanguageInstructionConformalCompiler
    bus: CertificateCRDT

    def admits(self, u, c, plan, t_r):
        if not self.hpc_e.admits(plan, ...):          # 几何∧规范∧负信息∧能量
            return False
        gamma = self.licc.conformal_set(u, c)
```

## 3. 实验设计

**平台与数据**
- 语言侧：ALFRED/RT-1/RT-2 风格任务 + 自建"歧义-危险"指令集（否定辖域、指代、量词辖域、时序、与规范冲突），每条标注真意图 `I*` 与安全后果；另构造**对抗性/分布漂移**子集（罕见措辞、ASR 噪声、方言、多语混用）。
- 中间件侧：Nav2 + MoveIt2 + Gazebo/Isaac，DDS 层注入故障：丢包、乱序、重复、重放、topic remap/namespace 改写、时钟偏斜 0–200ms、QoS 由 reliable 降级为 best-effort、节点供应链伪造。

**指标**
1. 不安全执行率（应按目标 ≤ 阈值）；2. 无澄清任务成功率（活性）；3. 澄清率；4. `Γ_NL` 经验覆盖（边际 + 风险分层条件）；5. CRDT 收敛性（随机到达置换后 fused-state 哈希是否相同）；6. 陈旧保守度（活性损失 vs 钟偏/QoS 违约的曲线）；7. 拜占庭注入成功类型（应是 DoS/活性损失，而非安全违约）；8. 控制路径延迟（CCM/HPC-LR 须 O(1)；LICC 离线 5–10Hz 注事件，不占 50Hz）。

**消融与基线**
- 点估计解析 vs `Γ_NL`；无 OOD 退化 vs OOD→全集；丢弃陈旧 vs 衰减陈旧；无 attestation vs attestation；无 topic 绑定；中心化 ζ vs CCRDT。
- 基线：v22；LLM + 静态规则过滤；ROS2 默认 QoS + 时间戳检查；标准集成 conformal。

**可证伪预测**
- P1：任务成功率相同时，点估计的不安全执行率显著高于 `Γ_NL` 折叠。
- P2：OOD→全集在对抗/漂移分层显著降低不安全率，活性损失有界（由证实/证伪）。
- P3：任意消息到达置换产生相同 fused-state 哈希（CRDT 顺序无关）。
- P4：衰减陈旧严格优于丢弃陈旧（更安全），代价是少量活性。
- P5：attestation + topic 绑定把拜占庭损害限制为 DoS，不产生虚假自由。

## 4. 本轮产物自检清单

- [ ] `Exec_v23 ⊆ Exec_v22` 在定理 934 的四个前提下成立；任一模块失效按 §3 只向更保守退化。
- [ ] 语言侧无点估计执行路径；OOD 必退全集；澄清只在跨越证书边界时触发。
- [ ] 中间件侧无"丢弃负证据"路径；正/负证据衰减不对称；skew 在新鲜度中减去。
- [ ] CRDT 合并幂等/交换/结合，重复与重放不改变 fused-state。
- [ ] 覆盖缺口（命题 935）被显式记录在证书元数据，未被默认宣称解决。

## 5. 本轮最大风险（与想法区一致）

**一句话**：语言侧的 conformal 覆盖只是**边际**保证、中间件侧的新鲜度只是**契约**保证；在最需要它们的**罕见/对抗性指令 + QoS 降级/钟偏**工况下二者可能同时失守，系统会以一条**完全合规、可审计、可溯源**的证书链执行一次"**基于过期证据、且把人的意图静默折叠错了**"的动作——即"证书齐备的错事"。
