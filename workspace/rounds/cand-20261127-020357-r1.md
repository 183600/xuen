## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（全身控制 → 接口里有一根「没人插的线」）**
直觉：这是一台人形机器人，但几乎所有队伍都会把它当「固定底座的双臂 + 夹爪」来训。理由很充分：32 任务都是桌面操作，示教里 `pivot` 恒定（F23），行为克隆自然学会「输出常数 pivot」。但接口强制要求 pivot（F20），官方模型也明确支持全身操作（F24）——这说明组织者预期全身是可用维度，只是**示教没有把它叫醒**。核心反直觉点：**全身控制的价值不在「走路」，而在把「够不到 / 看不清 / 放不稳」这三类失败变成可控的基座/身高/俯仰微调；它是一类「泛化期干预」，不是「标称期技能」。** 因为示教是固定基座，任何 pivot 运动都是分布外（OOD）动作，必须最小、可回退、可门控。

**灵感 2（需求洞察 → 接口与数据 schema 就是评测者的「隐性需求说明书」）**
直觉：我们一直在猜评测者要什么，但评测者其实把需求写进了两处「不会说谎」的地方：(a) **接口**——强制 pivot 说明他们要全身能力，只暴露 pivot 说明他们要的是高层指令而非低层力矩，不暴露头部说明主动视角不是必答项（F20/F26）；(b) **数据 schema 与统计**——每个任务用不用双手、腰动多少、EE 工作空间多大、物体多高，都能从公开数据直接算出来（F21/F25）。需求洞察的正确姿势不是再写一份「用户故事」，而是建一张**「需求—能力—计分」可追溯矩阵**：每个创新点必须指向某任务某轴的某个得分点，否则就是自嗨。核心反直觉点：**最强的需求洞察是「发现大部分任务根本不需要全身」——于是把全身预算只花在少数真正够不到的任务上，而不是全局启用。**

**碰撞（本轮统一命题）**
全身控制提供「多出来的自由度」，需求洞察提供「该不该用、用在哪、用多少」的判据。二者合起来给出一个可证伪的假设：**全身通道的最优策略是「默认休眠 + 触发式最小干预」**——标称场景输出示教学到的常数 pivot（保证分布内），仅当需求矩阵判定「当前失败是可达/高度受限」时，才在受限包络内调整 height/pitch/小位移，并在置信下降时回退。这把「全身控制」从高风险炫技降级为**有边界的泛化补丁**，与「需求洞察」的可追溯性天然咬合。

## 2. 对上一轮痛点的增量修订

- 新增 **P9（全身通道休眠）**：示教 pivot 恒定（F23）→ 行为克隆必然学出常数 pivot；不主动干预则全身自由度等于不存在。
- 新增 **P10（OOD 全身风险）**：任何 pivot 运动都偏离示教分布；全身自由度越多、方差越大，可能伤害原本能成的任务（与 P3 干扰、P6 稳定性叠加）；且 obs 无 base IMU（F26），干预对平衡开环。
- **P2（泛化缺口）再细化**：位置轴/高度轴的失败可能不是「策略不会」，而是「物理够不到」——这类失败靠增广/检索都补不了，只能靠 base/height 干预；但需先用需求矩阵区分「够不到」与「不会做」。
- **P7（先手窗口）补充**：`action.pivot` 被参考实现置零（F20），多数队伍会照抄 → 全身维度是低竞争的差异化点，但也是低容错的点。

## 3. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

- **Q9（全身必要性图谱）**：对 32 任务 × 5 泛化轴，哪些失败是「可达/高度受限」（全身可解）、哪些是「感知/技能不会」（全身无解）？用公开数据能算出多可靠的「能力签名」（双手指数、EE 工作空间、腰/高度使用范围）？
- **Q10（pivot 语义与安全包络）**：`pivot` 7 维的真实含义、单位、限幅与执行方式是什么？在不破坏平衡/不触发保护的前提下，height/pitch/小位移的安全子集与最大步长是多少？如何用最小真机预算确认？
- **Q11（需求可追溯与评分逆向）**：能否把「任务 wiki 得分点 + 数据 schema/统计 + 示例视频」合成机器可读的 `task_requirements`，并用它给创新点排序/修剪？在合规前提下，单任务通道能否作为「评分函数 oracle」反推部分分曲线？

## 4. 设计原则（新增 PR6/PR7，其余保留）

- **PR6 需求可追溯律**：任何创新点必须写成「任务 τ × 轴 a × 得分点 s × 能力 c × 证据 e」的可追溯条目；无法落到计分需求上的，降级或修剪。PR1 管「对准计分轴」，PR6 管「证明你确实对准了」。
- **PR7 全身最小干预律**：全身自由度默认输出示教先验（常数/标称 pivot）；仅在需求矩阵判定为可达/高度受限时，于受限包络内做单轴、小步、可回退的干预；禁止全局连续全身策略。理由：示教固定基座（F23），全身运动是 OOD（P10）。
- PR1–PR5 保留。

## 6. 本轮最大风险

**一句话**：全身方案建立在一条**尚未确认的 7 维 pivot 解码**（F22）与「OOD 的 pivot 运动净收益为正」的假设上——而示教恰恰是固定基座（F23）、obs 又无 base IMU（F26），一旦解码错误或干预过激，就会把一个本来能成的任务主动推下桌，属于「自伤型」风险；因此必须先解码、先 L0、先回退，且默认 pivot 休眠。

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2）

> 检索日期：2026-11-26/27（前两轮）、2026-11-27（本轮）；来源见 §5。承接 v1.1：新增 I10–I12，深化 I1/I2/I5/I8/I9，I7 裁撤出计分路径。清单只增改不重置。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I10 需求—能力—计分可追溯矩阵 + 评分逆向 ★★★★★（新）
- **动机**：第 2 轮已把「考纲」降级为可校准问题（I1），但缺一张**把需求翻译成能力、再翻译成得分点**的账本；结果容易出现「做了很酷的模块，却不落在任何得分点上」（PR6 要治的病）。
- **与现有方案差异**：别人读 wiki 写人话笔记；本点产出**机器可读**的 `task_requirements.yaml`，并用公开数据算每个任务的「能力签名」，让「该不该做某创新」变成可计算问题，而不是拍脑袋。
- **技术可行性**：高。三路证据融合：①任务 wiki/挑战页得分点文本（LLM 结构化 + 人工校对）；②HF datasets-server 的 schema/统计/抽样行（无需下载全量即可算签名）；③官方示例视频/截图作锚点。
- **所需资源**：1 人周工程 + 1×GPU 日（统计批处理）；无真机即可完成 80%。
- **落地步骤**：
  1. 定义 `Requirement` schema（见 §1.3）：任务、指令、得分点、五轴、能力、证据、权重；
  2. 写 `capability_signature.py`（见 §1.1），对 32 任务批量算签名；
  3. 生成覆盖看板：每个创新点 → 它覆盖的 (τ, a, s) 三元组；孤儿创新标红；
  4. 评分逆向：优先解析 wiki/JS 端点拿得分点清单；单任务通道**仅在规则允许且预算内**做「截断轨迹 → 读步骤分」的 oracle 探测（合规见 §4）；
  5. 把看板接入 I8 的 L0/L1/L2 排序，作为「值不值得测」的准入。
- **风险**：wiki 与真实评分仍有偏差（缓解：示例截图 + 少量 oracle 探测校准）；把需求矩阵做成「又一个文档」而不驱动决策（缓解：看板直接作为 I8 排序输入，孤儿创新强制降级）。

### I11 全身「最小干预」可达域扩展 ★★★★（新，硬门控）
- **动机**：位置轴/高度轴的失败里，有一部分是**物理够不到**（F23 示教固定基座，策略从未学过伸身/升降）；这类失败无法靠 I1 增广或 I9 检索补，只能动 base/height。而接口强制提供 `action.pivot`（F20），是现成的杠杆。
- **与现有方案差异**：多数队伍把 pivot 置零（照抄 example，F20）；盲目全身策略又把 OOD 方差拉满。本点是**默认休眠 + 需求触发 + 受限包络 + 零回退**：只在 Q9 判定「可达/高度受限」的任务上，做单轴小步干预。
- **技术可行性**：中。前提是 F22 的 pivot 解码被确认；干预本身是低维规则/小控制器，不需重训大模型。obs 无 base IMU（F26）→ 只能开环小步，恰好与「最小干预」一致。
- **所需资源**：解码与仿真验证 1 人周；真机仅用于 Q10 的安全包络确认（少量）。
- **落地步骤**：
  1. **解码**：用数据集抽样确认 `pivot=[vx,vy,ωz,roll,pitch,yaw,height]`（§1.2），在本地 stub/仿真里看 lower_body 响应；
  2. **包络标定**：测出 height/pitch/小位移的安全盒（最大步长、速率、回退阈值）；
  3. **触发**：目标 EE 距离/高度超出机械臂舒适工作空间（用能力签名与在线检测判定）才启用；
  4. **回退**：置信下降、超时、视觉校验失败、或 I4 检测到人工介入 → 立即回标称 pivot；
  5. **验证**：L0 先证「不伤标称」；L1 只在 2–3 个可达受限任务上测；L2 真机确认净增益。
- **风险**：pivot 解码错误或执行语义不符（缓解：先解码再上真机，本地 stub 只验格式不验动力学，须仿真/单任务确认）；OOD 干预自伤（缓解：硬门控 + 零回退 + 默认休眠）；无 base IMU 导致开环失衡（缓解：只做 quasi-static 的 height/pitch，位移仅极小步并靠视觉校验）。

### I12 双手机会协调 + 非操作臂环境改造 ★★★★（新）
- **动机**：32 任务明确含「双手协调」（官网文案），干扰轴（轴 3）需要清障；单臂策略把另一只手当摆设，浪费一半执行器。
- **与现有方案差异**：别人要么全程双臂同步（难协调），要么完全单臂；本点用能力签名识别「双手机会任务」，给非操作臂分配**小而确定的角色**：清障、持物/扶稳、支撑/抵住。
- **技术可行性**：中-高。先做规则化原语库（移到一旁/保持/抵住），不急于学双臂联合策略；与 I3 的关键点伺服共用感知。
- **所需资源**：1 人周；真机少量（主要 L1）。

## 1. 关键伪代码与严谨定义

### 1.1 能力签名：从公开数据算「需求」（I10）

对任务 τ 的帧集 D_τ，记 `p_L(t), p_R(t) ∈ R³` 为左右 EE 在 base 系的位置（直接取 `observation.state.*_ee_pose_gripper_base` 前三维），`g_L, g_R` 为夹爪开度，`w(t)∈R³` 为 waist 关节：

```python
def capability_signature(ds):            # ds: 某任务的全部帧（可流式）
    reach = q95([max(norm(pL), norm(pR)) for pL,pR in zip(ds.pL, ds.pR)])
    vert  = q95(ds.z) - q05(ds.z)                       # EE 高度跨度
    bim   = mean((gL > 0.5*gmax) & (gR > 0.5*gmax))      # 双手同时持物指数
    waist = max(max(w,axis=0) - min(w,axis=0))          # 腰使用范围
    pv    = mean(var(pivot[:,j]) for j in range(7))     # pivot 方差（预期≈0，F23）
    return dict(reach=reach, vert=vert, bimanual=bim,
                waist=waist, pivot_var=pv)

def whole_body_necessity(sig, R_safe, H_safe, pos_axis_shift):
    # 可达受限：EE 工作空间或高度跨度超出机械臂舒适区，或位置轴偏移超臂展
    z = alpha*(sig.reach - R_safe) + beta*(sig.vert - H_safe) + gamma*pos_axis_shift
    return sigmoid(z)                     # ∈(0,1)，>0.5 视为「全身可能有用」

def bimanual_opportunity(sig, semantic_flag):
    return max(sig.bimanual, semantic_flag)   # 语义标注优先
```

> 严谨性说明：签名只依赖公开 schema（F21/F25），**不需要下载全量**即可用 datasets-server 的统计/抽样行估计；`reach/vert` 用分位数而非均值，避免被少数极端帧拉偏。签名是「必要性先验」，最终仍由 L0/L1 裁决（PR6）。

### 1.2 pivot 解码与门控干预（I11）

```python
# 假设（F22，置信中）：pivot = [vx, vy, wz, roll, pitch, yaw, height]
NOMINAL = np.array([0, 0, 0, 0, 0.15, 0, 0.74])   # 示教常数（F23）

class PivotGatedReach:
    def __init__(self, req, envelope):            # req: task_requirements[τ]
        self.req, self.env = req, envelope        # env: 安全盒（每维 min/max/rate）
        self.active, self.t = False, 0

    def step(self, obs, arm_chunk):
        if not self.req.reach_limited:            # 需求矩阵判定不需要 → 休眠
            return NOMINAL
        target = self.req.target_xyz(obs)         # 检测/语言给出的目标点
        if self.env.within_arm(target, obs.ee):   # 臂可达 → 不干预
            return self.rollback()
        # 单轴、小步、受限：优先 height，其次 pitch，最后极小位移
        cmd = self.env.clip_step(NOMINAL, target, obs.ee)
        if self.env.unstable(obs) or self.t > self.env.max_steps:
            return self.rollback()
        self.active, self.t = True, self.t + 1
        return cmd

    def rollback(self):
        self.active, self.t = False, 0
        return NOMINAL.copy()
```

关键约束（由 F26 推出）：obs 无 base IMU → `unstable()` 只能用可观测代理（臂/腰关节突变、目标仍在视野、视觉位移一致）；因此只允许 quasi-static 的 height/pitch，位移仅极小步且靠视觉校验。
