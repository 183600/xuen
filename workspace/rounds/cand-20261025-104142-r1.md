# 第 8 轮（承接第 7 轮；新循环第 1 轮）· WRIST-V：腕部是验证器，延迟是预算，论文是测量学

> 检索/复核日期：**2026-10-25（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API。状态文件原为第 7 轮 PILOT-GPR；本轮按第 8 轮续写，不推倒重来。三个灵感词是「论文发表」「腕部相机」「低延迟推理」。

**主判断：腕部相机不是“再一路输入”，而是一个有截止时间的高精度接触传感器。** 它能把系统的精度极限 \(c\) 从 3.85 mm 降到 2.35 mm（[S14]），但在 UniBot 的远程 API 里，腕部图像只在 `get_action` 被调用时到达，动作块又被评测端整段开环执行——腕部看到的是“过去”，动作执行的是“未来”。更长的 chunk 降低推理频率，却把腕部的有效反馈延迟推到 267–533 ms；更短的 chunk 提高反应性，却让推理/网络成本回到临界路径。**所以真正的低延迟问题不是“模型再快 20%”，而是“把腕部信息在截止时间前送到，并在送不到时不要让腕部污染动作”。**

**本轮要押的不是一个更大的 VLA，而是一套“看—做—验证”的时间预算器：WRIST-V。** 它把每个固定动作块当成一个时间量子，在“执行任务 / 主动探针 / 腕部验证”之间分配；用腕部可靠性门控决定信不信腕部；用推测式候选块在机器人执行当前块时预先算好下一块，把推理延迟藏到执行窗口里；用延迟/视角扰动训练让策略学会“腕部迟到时怎么退化”。论文层面，这可以写成一篇测量学 + 方法的文章：**The Wrist Deadline: When Close-Up Vision Arrives Too Late**，并发布 `UniBot-Wrist` 诊断基准。

## 0. 本轮先纠正四件事

### 0.1 排名是成功率优先，步骤分只是 tie-break

官方手册 1.2 写得很清楚：实时榜按 32 个任务的总平均成功率排序；成功率相同才看总平均步骤分；仍相同则更早提交者靠前（[S1]）。第 7 轮把“成功率与步骤分综合排序”当成目标函数，需要修正。

这不是文字问题，而是优化目标问题：

```text
主目标 = P(整条 episode 成功)          # 成功 = 全部评分步骤完成
辅助   = E[步骤分]                     # 只在成功率打平时决定名次
诊断   = 步骤级完成率                  # 用来决定把预算花在哪一步
```

终局放置/插入仍然是 32/32 任务的成功闸门，但它重要的原因是“它是闸门”，不是“它占 39.8% 步骤分”。任何只提高部分步骤、不提高整条成功率的改进，对排名几乎没有价值。

### 0.2 动作块是“固定长度 + 整段执行”，不能中途打断

提交 README（[S4]）明确：

- `action_chunk_size` 在 `metadata` 里固定，是每个动作数组的 leading time-axis 长度；
- 评测端执行 index 0，然后按顺序执行其余动作，**直到再次调用 `get_action`**；
- 策略不能在 chunk 执行到一半时收到新的腕部图像，也不能让评测端“执行前 2 步就停”。

这条约束直接推翻第 7 轮 SVL 伪代码里的 `for chunk in stream(policy.act(...)): if predicate_met: break`：**在真实接口里，chunk 一旦返回就会被执行完，不能中途 break。** 第 7 轮的 settle-verify 必须升级为“块边界验证”，而不是“块内闭环”。

于是有效反应延迟不是推理时间，而是：

\[
A_k = L_{capture} + L_{infer} + L_{network} + H/f_c + Q
\]

其中 \(H\) 是固定 chunk 长度，\(f_c=30\) Hz，\(Q\) 是排队/并发延迟。**腕部的有效反馈率是 \(1/A_k\)，不是 30 Hz。** \(H=8\) 时，仅执行就 267 ms；加上推理/网络，腕部在终局接触时已经晚了 300–450 ms。

### 0.3 腕部的价值是有条件的，不是“有腕部就更好”

三篇 2026 年论文把这件事钉死了：

- **WARP-VLA**（[S10]）：腕部相机随手臂运动，安装/视角的小变化就会改变精细几何线索；在腕部视角扰动下，WARP 把 \(\pi_{0.5}\) 的平均成功率从 **39.2% 提升到 78.3%**。这说明腕部视角漂移是 first-order distribution shift，不是噪声。
- **FoveaVLA**（[S12]）：把腕部相机替换成学习式 foveation，在四个真机任务套件上从 \(\pi_{0.5}\) 的 **52.1% 提到 70.8%（单外视角）/ 77.1%（双外视角）**。腕部不是无条件有益；当它挡住/限制视野或被误用时，去掉它反而更好。
- **VersaCamVLA**（[S11]）：相机数量/位姿可变，用 wrist-augmented pose sampling 把腕部运动当成免费位姿多样性。腕部的正确用法是“可配置、可校准、可退化”，不是“固定四路一起喂”。

所以本轮不押“更用力用腕部”，而押 **“腕部可靠性门控 + 截止时间调度”**：该信时信，不该信时退；该看时看，该做时做。

### 0.4 榜单仍是占位，“榜首不到 30%”不能当真实基线

`leaderboard.html` 与 `runs.html` 仍是 Coming Soon；`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，8 个模型 ×32 任务的数字是脚本生成（[S5][S6][S7]）。用户所说“榜首不到 30%”来自这份占位数据（MolmoAct2 29.7、WALL-OSS-0.5 28.5、DreamZero 27.9），**不是真实团队成绩**。

它只能当压力测试：如果真实头部也在 30% 量级，+5pp 是数量级跃迁；如果真实头部是 50%，+5pp 仍是显著进步。两种情景下，“腕部截止时间”这个机制都值得做，但不能用占位数字证明它一定赢。

## 1. 三个灵感词，各自钉到硬事实上

### 1.1 论文发表：缺的不是又一个模块，而是“腕部价值”的测量学

2026 年的腕部/VLA 文献已经很多，但缺口很具体：

- WARP 研究“视角变了怎么办”，没有研究“腕部图像晚到 300 ms 怎么办”；
- VersaCam 研究“相机配置可变”，没有研究“固定 API 下如何分配看与做”；
- Fovea 研究“去掉腕部”，没有给出“什么时候该保留腕部”的判据；
- RTC/A2C2/AutoHorizon/AAC 研究延迟/执行 horizon，但假设可以异步更新、可以逐步修正、可以动态截断；
- TokenPB 研究候选块自验证，但没有把“腕部观测年龄”和“固定 chunk”作为约束；
- SV-VLA/SpecVLA 研究 speculative verification，但需要每步新观测或额外小模型，和 UniBot 的“块边界才有新观测”不同。

**可发表的空白**：在“固定动作块 + 只在块边界有观测 + 腕部高分辨率但可漂移”的远程真机设置里，腕部信息的价值如何随观测年龄衰减？如何在不违反单模型/固定接口的前提下，把“看”和“做”统一到同一个时间预算里？这是一个真实的系统—学习交叉问题，不只是竞赛工程。

论文不需要赢榜才能成立：即使最终成功率只提升 3–5pp，只要能把“腕部在什么延迟下有用/有害”“门控与推测式预取各自贡献多少”讲清楚，就是一篇有数据、有反例、有方法的 CoRL/RSS/ICRA 级工作。

### 1.2 腕部相机：唯一能“自己瞄准”的高精度接触传感器

腕部相机的特殊性不只是近景，而是它**装在执行器上**：

- 它随夹爪运动，能看见夹爪-物体接触面、间隙、滑移、遮挡和变形；
- 它可以通过手臂运动主动改变视角——**看哪里，本身就是一个动作**；
- 它也随安装/关节误差漂移，视角变化会破坏精细几何（WARP）；
- 它的精度收益有定量证据：精度律论文（[S14]）报告，去掉腕部相机把精度极限 \(c\) 从 2.35 mm 提到 3.85 mm；在接近 \(c\) 的装配/插入任务里，达到同样成功率所需演示数会急剧增长。

这给出一个很锋利的推论：

```text
终局插入/堆叠/闭合的容差接近 c
→ 没有腕部，靠加数据几乎买不到精度
→ 有腕部，但腕部晚到/视角漂移，同样买不到精度
→ 真正稀缺的是“及时且可信的腕部观测”
```

### 1.3 低延迟推理：不是 FLOPs，是“观测年龄”

MolmoAct2（[S15]）在单张 H100、action horizon 10 的 LIBERO 设置下，连续动作路径经缓存 + CUDA Graph 达到 **55.79 Hz**（原 23.02 Hz），Think 版本 12.71 Hz；离散动作路径只有 14.17/6.82 Hz。这看起来“已经够快”，但 UniBot 的延迟不是单机推理延迟：

- 远程 API：网络 RTT + 图像传输 + 服务排队；
- 四路 480×640 RGB：payload 不小，`image_resize` 和 `obs_delta_indices` 会直接影响传输时间；
- 固定 chunk：推理再快，也要等 chunk 执行完才有新观测；
- N 台机器人并发：共享后端会被其他端口排队（Armory 的调度问题，[S25]）。

所以“低延迟”应拆成三个量：

| 量 | 含义 | 对腕部的影响 |
|---|---|---|
| \(L_{infer}\) | 单次前向 | 决定块边界响应速度 |
| \(L_{network}\) | 观测上传 + 动作下发 | 远程部署的固定税 |
| \(H/f_c\) | 开环执行窗口 | **腕部信息的主要老化来源** |
| \(A_k\) | 观测年龄总和 | 腕部有效反馈率 \(1/A_k\) |

当 \(A_k\) 大于任务的接触时间常数 \(\tau_{task}\) 时，腕部闭环已经来不及；此时继续把腕部当闭环信号，只会把“迟到的纠正”变成“过冲/振荡”。正确的做法是：**要么缩短 \(A_k\)（小 chunk + 推测预取），要么把这一块时间用于主动探针/验证（look），要么退化为开环柔顺动作（act without wrist）。**

## 2. 主判断：腕部截止时间与“看—做”预算

### 2.1 一个可检验的失败模型

把终局接触失败拆成四类：

| 失败 | 机制 | 腕部能否救 | 截止时间 |
|---|---|---|---|
| W1 抓空/滑移 | 夹爪闭合但物体没跟上来 | 能（看物体是否随夹爪动） | 抓后 200–500 ms |
| W2 对位偏差 | 插头/试管/杯沿偏离 2–5 mm | 能（近景相对位姿） | 接触前 100–300 ms |
| W3 插入/闭合未到位 | 看见“到了”，实际没卡住 | 能（看间隙/变形/末端） | 接触后 100–300 ms |
| W4 视角/遮挡 | 腕部被夹爪/物体挡住，或安装漂移 | 不能直接救，需要换视角/探针 | 随时 |

这四类里，W1/W2/W3 都要求腕部在 **100–300 ms** 内形成闭环；而 \(H=8\) 的 UniBot 策略在块边界才有一次腕部观测，执行窗口就 267 ms。**腕部最需要的时候，恰好是它最晚的时候。** 这是本轮的核心矛盾。

### 2.2 三个可证伪假设

- **H1（截止时间）**：腕部对终局成功率的边际收益随观测年龄 \(A_k\) 单调下降；存在任务相关的 \(A^*\)，超过后腕部收益转负。
- **H2（门控）**：腕部可靠性门控（可信时用、不可信时退）优于“总是用腕部”和“总是不用腕部”，尤其在视角扰动/遮挡下。
- **H3（推测）**：在执行当前块时按结果类预生成下一块应急候选，可以把块边界响应延迟压到选择延迟，从而让 \(H=4\) 的短块在远程 API 上可行；其成功率优于同步 \(H=8\)，且不牺牲吞吐。

如果 H1 不成立（腕部晚到也无所谓），本轮退回“纯门控 + 探针”；如果 H3 不成立（预取候选匹配不上），退回“固定 \(H=4\) + 轻量验证”，论文仍可写负面结果。

### 2.3 为什么不是“直接上 \(H=1\)”

\(H=1\) 让腕部每个控制步都有新观测，但代价是：

- 30 次/秒的远程请求；
- 每次四路图像，带宽可能到 100 MB/s 量级；
- 30 次/秒的完整 VLA 前向，即使 55 Hz 的 H100 也会被多机器人并发拖垮；
- 网络抖动会直接变成控制抖动。

所以我们需要的是 **“短块 + 预取 + 边界选择”**，而不是“无块 + 每步重算”。这也是 WRIST-V 与 RTC/A2C2 的关键区别：后者假设可以流式/逐步更新；UniBot 的接口不允许，我们只能在块边界做文章。

## 3. WRIST-V 方案轮廓

```text
                  ┌────────────── 固定时间量子 H/f_c ──────────────┐
                  │                                                  │
obs_k ──► WRG 腕部可信度 ρ_k ──► PDS 看/做调度 ──► 执行块 A_k ──► obs_{k+1}
                  │                    │                             │
                  │                    ├─ ACT：任务动作块            │
                  │                    ├─ PROBE：主动腕部探针        │
                  │                    └─ VERIFY：落点/抓持验证      │
                  │                                                  │
                  └─ SCS 推测式应急树：在执行 A_k 时按结果类预生成 A_{k+1} 的候选
                       （按预测的腕部结果分叉；obs_{k+1} 到达时选最匹配的）
```

五个组件：

1. **WRG（Wrist Reliability Gate）**：从模糊、曝光、遮挡、运动模糊、时序一致性、与高位相机的特征一致性估计腕部可信度 \(\rho_k\)；低于阈值时把腕部 token 置为“缺失”，回退到高位相机/fovea crop。训练时做腕部 dropout、延迟、遮挡、视角扰动，让模型学会“没有腕部也能做”。
2. **AWP（Active Wrist Probe）**：当 \(\rho_k\) 低或抓持/对位不确定时，用一个固定 chunk 执行 0.3–1.0 s 的探针（抬 1–2 cm、倾 15°、侧移 2 cm、轻压后撤），主动让腕部看见接触面；下一块根据探针结果分支（继续/重抓/重对位）。探针不是“浪费”，而是用时间买信息。
3. **SCS（Speculative Contingency Selection）**：当前块 \(A_k\) 返回后，结果预测头给出它的 \(K\) 类可能结果（滑移/稳定/偏左/偏右/到位/未到位）；在执行窗口里，用同一策略为每个可能结果预生成下一块，形成应急树。`obs_{k+1}` 到达时，用实际腕部嵌入匹配结果类，选对应下一块；匹配度低则回退到实时推理。
4. **PDS（Phase-aware Deadline Scheduler）**：用 SSG 的当前步骤、剩余 180 s、任务权重、腕部可信度、候选树匹配度，决定这一块是 ACT / PROBE / VERIFY，以及候选预算 \(M\)。终局接触优先短块/探针；搬运段优先长块/吞吐；时间不够时退回保守开环。
5. **DWT（Delayed Wrist Training）**：训练时随机把当前腕部帧替换成 \(t-\Delta\) 的旧帧（\(\Delta\) 覆盖 0–533 ms），并做视角/遮挡/曝光扰动；让策略在“腕部迟到”时仍然能输出可执行动作，而不是学过拟合当前帧。

一句话：**把腕部从“每帧都信的输入”改成“有截止时间的证据”；把固定 chunk 从“只能开环执行”改成“执行时预取、边界时选择”；把探针从“浪费动作”改成“主动购买信息”。**

## 5. 论文计划（论文发表不是赛后补写，而是赛前设计）

**工作标题**：*The Wrist Deadline: When Close-Up Vision Arrives Too Late*

**三个贡献**：

1. **测量**：定义观测年龄 \(A_k\)、腕部有效反馈率、任务截止时间 \(\tau_{task}\)；在 32 个 UniBot 任务上测量“腕部收益 vs 延迟/视角扰动”的曲线，给出腕部从有用到有害的转折点。
2. **方法**：WRIST-V——可靠性门控 + 主动探针 + 推测式应急选择 + 看/做调度；不引入第二个任务模型，所有学习件在同一 checkpoint 内。
3. **基准**：`UniBot-Wrist`——32 任务 × 5 类腕部扰动（位姿偏移、遮挡、模糊、曝光、掉线）× 4 个延迟档（\(H=2/4/8/16\)），报告成功率、步骤分、观测年龄、腕部依赖度、探针率、响应延迟 p99。

**可证伪的实验矩阵**：

| ID | 配置 | 验证 |
|---|---|---|
| E0 | WLA/π0.5 基线，固定 H=8 | 复现 |
| E1 | E0 + WRG | 门控是否在扰动下减少伤害 |
| E2 | E1 + DWT（延迟/视角扰动训练） | 迟到/漂移下的鲁棒性 |
| E3 | E2 + AWP | 抓空/对位失败是否下降 |
| E4 | E3 + SCS（M=1/2/4/8） | 应急匹配率、响应延迟、成功率 |
| E5 | E4 + PDS | 看/做预算是否优于固定策略 |

## 6. 风险与合规

- **预取是否被允许**：API 允许策略服务在自己的机器上做任何计算；预取只是把计算提前，不改变接口。需在模型卡/技术报告披露，避免“隐藏第二个模型”的误解。
- **单模型边界**：WRG/PDS 是确定性代码；结果预测器/探针分类器若是学习件，必须作为同一 checkpoint 的轻量头，不单独训练一个任务模型。若审计严格，先做纯确定性版本（光流/模糊/遮挡 + 探针），再逐步加头。
- **探针耗时**：每个探针 0.3–1.0 s；每任务上限 2 次；长程任务（T16/T17/T31）上限 1 次；由 180 s 守卫兜底。
- **腕部视角漂移**：N 台机器人可能安装不一致；WRG 必须在线估计，不能假设校准完美；训练覆盖扰动。
- **预取误匹配**：匹配度低必须回退；回退率是核心监控指标；宁可回退，不可执行错误分支。
- **榜单噪声**：真实榜单未发布；不要把占位榜当基线；所有增益用配对 CI 报告。
- **外部数据**：L2L 仍默认 OFF；论文基准优先用官方数据 + 仿真扰动 + 调试槽，不依赖未授权数据。

## 1. 事实核对与纠错

### 1.1 排名：成功率优先，步骤分只是 tie-break

官方手册 1.2（[S1]）：实时榜按 32 个任务的总平均成功率排序；成功率相同才按总平均步骤分；仍相同则提交日期早者靠前。每个任务 10 次，5 类泛化（位置/干扰物/背景/未见物品/人为干扰）各 2 次；单次最多 180 s。

第 7 轮把“成功率与步骤分综合排序”当成目标函数，是一个需要明确修正的错误。正确写法：

```text
主目标 = P(整条 episode 成功) = P(全部评分步骤完成)
辅助   = E[步骤分]（只在成功率打平时决定名次）
诊断   = 步骤级完成率（决定重试预算与探针位置）
```

终局放置/插入仍是 32/32 任务的成功闸门；它重要的原因是“闸门”，不是“39.8% 步骤分”。任何只提高部分步骤、不提高整条成功率的改进，对排名几乎没有价值。

### 1.2 动作块是固定长度、整段执行，块内没有新观测

提交 README（[S4]）的原文约束：

- `action_chunk_size` 是 `metadata` 的固定字段，`int >= 1`；
- `get_action` 返回的每个动作数组形状为 `(T_a, ...)`；
- index 0 先执行，其余按顺序执行，**直到评测端再次调用 `get_action`**；
- 评测端记录每一步的响应延迟和内容，并可能用于结果可信度评估。

这意味着：

\[
\text{块内可观测次数} = 0,\qquad
\text{腕部有效反馈率} = \frac{1}{L_{capture}+L_{infer}+L_{network}+H/f_c+Q}
\]

第 7 轮 SVL 伪代码里的 `for chunk in stream(...): if predicate_met: break` 在真实接口里不成立。**块内不能 break；只能在块边界验证，并决定下一块。** 这是本轮所有设计的硬约束。

## 2. 形式化：固定量子下的“看—做”POMDP

### 2.1 观测年龄

在块边界 \(k\)，观测 \(o_k\) 在时刻 \(t_k\) 捕获；策略在 \(t_k+L_{infer}+L_{network}\) 返回动作块 \(A_k\)；评测端从 \(t_k+L_{infer}+L_{network}\) 开始执行 \(H\) 步，执行到 \(t_k+L_{infer}+L_{network}+H/f_c\)。因此块末的观测年龄：

\[
A_k = L_{capture} + L_{infer} + L_{network} + \frac{H}{f_c} + Q_k
\]

其中 \(L_{capture}\) 是图像采集/编码，\(Q_k\) 是并发排队。腕部的有效反馈率：

\[
f_{wrist} = \frac{1}{A_k}
\]

如果任务在接触前需要以速度 \(v\) 接近、允许误差 \(\epsilon\)，则粗略的接触时间常数：

\[
\tau_{task} \approx \frac{\epsilon}{v}
\]

\(\tau_{task}\) 不是常数：插入/对位小、堆叠/放置大；必须从演示和调试槽估计。**当 \(A_k > \tau_{task}\) 时，腕部闭环已经过期；此时继续用腕部做纠正，会把迟到误差放大。**

### 2.2 固定量子的内容选择

`action_chunk_size` 固定为 \(H\)，所以不能在运行时改 horizon。但我们可以选择这一块 **做什么**：

- **ACT**：任务动作块，推进评分步骤；
- **PROBE**：主动探针，改变腕部视角/接触状态，获取信息；
- **VERIFY**：落点/抓持验证，确认上一步是否真的完成；
- **RECOVER**：按 NRB/SSG 回滚或重抓。

每个块的时间成本都是 \(H/f_c\)，但收益不同。把块类型记为 \(a\in\{\text{ACT},\text{PROBE},\text{VERIFY},\text{RECOVER}\}\)，则：

\[
U(a)=\underbrace{P_{succ}(a)}_{\text{成功主目标}}
+\epsilon\,\underbrace{E[step(a)]}_{\text{tie-break}}
-\lambda_t \frac{H}{f_c}
-\lambda_p\,\mathbb{1}[a=\text{PROBE}]
+\gamma\,\underbrace{I(a;\text{state})}_{\text{信息增益}}
\]

因为成功率是主排序，\(P_{succ}\) 的权远大于步骤分；\(\epsilon\) 取小值（如 0.01）。探针的 \(P_{succ}\) 可能暂时为 0（不推进任务），但信息增益 \(\gamma I\) 可以让后续块的成功率上升。**探针不是浪费，它是用固定时间量子购买信息。**

### 2.3 为什么“看”和“做”必须共享预算

腕部相机装在手臂上：要看得更清楚，往往要移动手臂；移动手臂又占用了本可以做任务的时间。这是 UniBot 特有的 **look-act tradeoff**：

- 抓空后，抬 1–2 cm 看物体是否跟随夹爪：0.3–0.5 s，能避免后面 5–10 s 的无效搬运；
- 插头对位前，倾 15° 看插孔：0.3–0.5 s，能避免反复插偏；
- 拉链/笔盒闭合前，侧移 2 cm 看齿/卡扣：0.3–0.5 s，能避免“以为合上”；
- 但这些探针不能无限做：每任务最多 2 次，长程任务最多 1 次，由 180 s 守卫兜底。

### 2.4 推测式应急选择

在执行 \(A_k\) 的 \(H/f_c\) 窗口里，服务器可以预计算下一块（评测端不会打断，计算不占关键路径）。设当前块 \(A_k\) 的结果预测分布为 \(\{y_j,p_j\}_{j=1}^K\)，对每个可能结果预生成下一块 \(A_{k+1}^{(j)}\)。当 \(o_{k+1}\) 到达时，实际腕部嵌入 \(z_{k+1}\) 用于匹配结果类：

\[
j^*=\arg\max_j\ \operatorname{sim}(z_{k+1},\hat z_j)
+\beta\log p_j
-\lambda\,\|\text{jerk}(A_{k+1}^{(j)})\|
\]

若 \(\max_j \operatorname{sim}<\tau_{match}\)，丢弃应急树，回退到实时推理。**匹配度是安全阀：宁可回退，不可执行错误分支。**

### 2.5 为什么不是 H=1

\(H=1\) 的腕部反馈率最高，但：

- 30 次/秒远程请求；
- 四路图像每次传输，带宽可能到 100 MB/s 量级；
- 30 次/秒完整 VLA 前向，多机器人并发下不可行；
- 网络抖动直接变成控制抖动；
- 评测端延迟/变异性会被记录，可能影响可信度。

所以目标是 **H=4（133 ms）+ 预取**，而不是 H=1。H=4 的执行窗口足够让预取完成一次 100 ms 级推理；块边界响应只剩选择 + 网络。

### 3.2 WRG：腕部可靠性门控

**目标**：在腕部图像模糊、过曝、被夹爪/物体挡住、视角漂移、或与高位相机不一致时，降低腕部权重，避免“垃圾进、垃圾出”。

**确定性线索**（无需学习，先上线）：

| 线索 | 计算 | 低可信信号 |
|---|---|---|
| 模糊 | Laplacian/Tenengrad 方差 | 低于任务阈值 |
| 曝光 | 像素截断比例、直方图熵 | 大片 0/255 |
| 遮挡 | 夹爪 mask / 目标 mask 覆盖率 | 接触面不可见 |
| 运动模糊 | 光流幅值 × 曝光时间 | 快速运动时 |
| 时序一致性 | 前一帧 warp 到当前帧的 photometric error | 突变/跳帧 |
| 视角一致性 | 腕部特征与高位相机投影/匹配 | 外参漂移、安装偏移 |
| 任务相位 | SSG 步骤 | 终局接触时要求更高 |

**轻量头**：在腕部 encoder 的 pooled 特征上接一个 2 层 MLP，输出 \(\rho_k\in[0,1]\)；用合成扰动（已知是否扰动）做监督，再用验证集做 isotonic/Platt 校准。**阈值按成功率选，不按分类准确率选。**

**使用方式**：

- \(\rho_k\ge\tau_{high}\)：正常使用腕部 token；
- \(\tau_{low}\le\rho_k<\tau_{high}\)：降权（token 乘 \(\rho_k\)）并加大高位相机权重；
- \(\rho_k<\tau_{low}\)：腕部 token 置为可学习的 `MISSING`，回退到高位相机 + fovea crop（从 480×640 高位图中裁剪交互区域，FoveaVLA/Fisheye 思路）。

**训练**：DWT 中随机 drop 腕部（p=0.1）、随机延迟、随机遮挡/曝光/模糊/透视；让模型见过“没有好腕部”的状态。

### 3.3 AWP：主动腕部探针

**目标**：当腕部看不清或不确定时，用固定块执行一个安全的探针，主动改变视角/接触状态，让下一帧腕部提供判别信息。

**探针库**：

| 探针 | 动作（EE 空间） | 回答的问题 | 典型任务 |
|---|---|---|---|
| LIFT | 沿 +z 抬 1–2 cm，停 0.2 s | 物体是否跟随夹爪？ | T01/T02/T08/T15/T27 |
| TILT | 绕腕部轴倾 10–20° | 接触面/插孔是否可见？ | T10/T26/T12/T19 |
| SWEEP | 侧移 1–2 cm 再回 | 夹爪/物体后面是什么？ | T09/T17/T31 |
| PRESS-RETREAT | 沿插入方向轻压 2 mm 再退 | 是否对准/卡住？ | T10/T26/T32 |
| REGRASP | 张开→微移→再闭合 | 是否抓偏/抓空？ | T01/T11/T13/T20 |

**安全**：所有探针限速、限幅、限时；在执行前用当前 EE/关节状态检查工作空间；遇到异常（超时/位置跟踪误差过大）立即回 ACT/VERIFY 的安全姿势。探针不是“探索未知”，而是“在已知任务里买一个判别信号”。

**探针结果分类**：用腕部光流/相对位移判断：
- 物体随夹爪动（在腕部图像中近似静止）→ 抓持稳定；
- 物体下滑/留在桌面（腕部图像中明显移动）→ 抓空/滑移；
- 接触面间隙缩小/消失 → 插入到位；
- 间隙不变/变大 → 未到位/偏。

**数据**：官方演示里有大量“抓-抬-放”段，可自动挖出正例；负例用仿真扰动/随机偏移/真实调试槽少量标注。先上线确定性光流版，再考虑学习头。

### 3.4 SCS：推测式应急选择

**核心**：块内不能改当前动作，但可以在执行期间算下一块。把“推理延迟”从关键路径移到执行窗口；把“块末腕部观测”同时当作上一块的结果验证和下一块的选择键。

**步骤**：

1. **当前块选择**（边界 \(k\)）：从策略采样 \(M\) 个当前块候选（不同 flow 噪声/检索上下文），按 TokenPB 式自验证/效用选一个 \(A_k^*\)；可选 AWP/VERIFY/NRB 块。
2. **结果预测**：结果预测头给出 \(A_k^*\) 的 \(K\) 类可能结果 \(\{y_j,p_j\}\)。可以是：
   - 离散类：稳定/滑移/偏左/偏右/到位/未到位；
   - 连续 latent：块末腕部 encoder 嵌入 + 物体-夹爪相对位移。
3. **应急预取**：在执行 \(A_k^*\) 时，对最可能的 \(K\) 个结果类，用同一策略生成“如果发生 \(y_j\)，下一块该怎么做”的候选 \(A_{k+1}^{(j)}\)，形成树。
4. **边界选择**：\(o_{k+1}\) 到达，计算实际腕部嵌入 \(z_{k+1}\) 与结果类 \(\hat z_j\) 的相似度；选 \(j^*\)，取对应 \(A_{k+1}^{(j^*)}\)；若匹配度低，回退实时推理。
5. **安全阀**：候选块必须通过与当前状态的动作连续性/工作空间检查；不满足则丢弃。

**训练**：
- 结果预测头用演示的块末腕部帧做自监督（对比学习/分类）；标签可从 EE/物体相对位移自动生成。
- 应急候选用离线 replay 评估：给定 \(o_k\)，执行 \(A_k^*\) 到 \(k+1\)，看实际结果类与预测是否一致；训练匹配分数。
- 不做“第二个任务模型”：结果预测头是同一 checkpoint 的轻量头；应急候选生成用同一策略。

**延迟收益**：

\[
S=\frac{L_{infer}+L_{network}}{L_{select}+L_{network}}
\]

若 \(L_{infer}=100\) ms、\(L_{network}=20\) ms、\(L_{select}=5\) ms，则 \(S≈4.8×\)。这允许 H=4 的短块在远程 API 上保持吞吐。

### 3.5 PDS：看/做调度器

**输入**：SSG 当前步骤 \(s_k\)、相位（transit/contact/verify）、剩余时间 \(R_k\)、腕部可信度 \(\rho_k\)、候选匹配度、探针次数、任务权重。

**输出**：块类型 \(a_k\)、候选预算 \(M_k\)、是否使用腕部。

**规则骨架**（先确定性，后可学习）：

```python
def schedule(s, phase, R, rho, match, probes):
    if R < R_min:                      # 时间不够，保守完成
        return ACT, M=1, wrist=rho>0.5
    if phase == "contact" and (rho < tau_low or match < tau_match):
        if probes < probe_limit:
            return PROBE, M=2, wrist=True
        return VERIFY, M=1, wrist=rho>0.5
    if phase == "verify":
        return VERIFY, M=2, wrist=True
    if phase == "transit":
        return ACT, M=1, wrist=rho>0.5
    return ACT, M=2, wrist=True
```

**候选预算**：时间充裕且不确定时 \(M=4/8\)；否则 \(M=1\)。应急树宽度 \(K=2\)（结果类数）；匹配失败回退。

**注意**：PDS 不改变 \(H\)。\(H\) 是提交时选定的全局参数（默认 4，离线 Pareto 选择）；PDS 只决定这一块的内容和候选预算。这是对 API 约束的尊重，不是回避。

### 3.6 DWT：延迟腕部训练

**延迟增广**：训练时以概率 \(p_\Delta\) 把当前腕部帧替换为 \(t-\Delta\) 的旧帧，\(\Delta\in\{0,1,2,4,8,16\}\) 帧（0–533 ms）；高位相机/状态保持当前。让策略学会“腕部迟到时，用本体/高位/开环柔顺”。

**视角/质量增广**：随机透视/裁剪/旋转/遮挡/曝光/模糊/掉线；用 VersaCam 的 WAPS 思路，从腕部运动产生位姿多样性，而不是只做 2D 仿射。

**模态 dropout**：腕部 p=0.1、任一路高位 p=0.1；训练 `MISSING` token，保证 WRG 回退时分布内。

**损失**：

\[
L=L_{flow}+\lambda_1 L_{outcome}+\lambda_2 L_{trust}+\lambda_3 L_{probe}+\lambda_4 L_{consistency}
\]

| 项 | 含义 | 起始权重 |
|---|---|---:|
| \(L_{outcome}\) | 结果预测（块末腕部 latent/离散类） | 0.1 |
| \(L_{trust}\) | 扰动/遮挡标签的可靠性 BCE | 0.05 |
| \(L_{probe}\) | 探针结果分类（稳定/滑移/到位） | 0.05 |
| \(L_{consistency}\) | 延迟/当前帧动作一致性（教师=当前帧策略） | 0.05 |

**训练课程**：

| 阶段 | 数据 | 目标 | 退出条件 |
|---|---|---|---|
| 0 | 真实 100% | 复现 WLA 基线 | held-out 不降 |
| 1 | +DWT（延迟/视角/dropout） | 迟到/漂移下不崩 | 延迟扫描成功率降幅 <5pp |
| 2 | +WRG 头 | 可信度校准 | ECE <0.1；门控在扰动下收益 >0 |
| 3 | +AWP 探针 | 抓空/对位失败下降 | 探针后二次成功率 >60% |
| 4 | +SCS 结果预测/匹配 | 匹配率 >70% | 回退率 <30% |
| 5 | +PDS 调度 | 看/做分配优于固定 | 本地终局 +5pp |
| 6 | 全量 + 蒸馏/量化 | 延迟达标 | 选择延迟 <20ms |

### 3.7 单模型与接口映射

**单模型**：一个 checkpoint 内含 VLM backbone、action expert、腕部 encoder、WRG 头、结果预测头、探针分类头。候选生成用同一 action expert；WRG/PDS/探针库/匹配是确定性代码。模型卡写清所有头与数据来源。

**接口建议**（默认配置，需实测）：

| 字段 | 建议 | 理由 |
|---|---|---|
| `control_space` | `ee` | 探针/放置都在 Cartesian 空间；便于限幅 |
| `action_chunk_size` | 4（备选 8） | 133 ms 量子；预取可隐藏推理；H=8 作为网络差时的退路 |
| `obs_delta_indices` | 高位 `[0]`、腕部 `[0]`、EE/夹爪 `[-2,0]` | 少传历史，降低 payload；速度由状态差分 |
| `image_resize` | 高位 `[240,320]`、腕部 `[480,640]` | 高位降带宽；腕部保留近景细节 |
| `token` | 官方 token | 双处校验 |

**N 端口**：共享后端 + 每端口独立状态/应急树；按端口隔离，避免 A 的候选树污染 B。用 Armory 的 deadline-aware 调度思想：预取任务优先级低于边界请求；边界请求优先，预取可取消。**不要让预取把边界响应拖慢。**

### 3.8 运行时伪代码

```python
class WristVPolicy:
    def reset(self):
        self.k = 0
        self.ssg = SSG()
        self.belief = Belief()
        self.tree = None
        self.probes = 0

    def get_action(self, obs):
        rho = self.wrg(obs)                       # 腕部可信度
        s, phase = self.ssg.update(obs.language, obs)
        R = 180 - elapsed()
        conf = 0.0

        # 1) 若上一块的应急树匹配，直接取下一块
        if self.tree is not None:
            j, conf = self.tree.match(obs.wrist, rho)
            if conf >= TAU_MATCH:
                action = self.tree.take(j)
                self.tree = self.prefetch(obs, action)
                return action
            self.tree = None

        # 2) 调度 + 当前块候选
        a, M, use_wrist = self.pds(s, phase, R, rho, conf, self.probes)
        cands = self.policy.sample(obs, a, M, use_wrist)
        cands = self.safety.filter(cands, obs)
        best = self.select(cands, obs, a)

        # 3) 返回当前块；执行期间对当前块的预测结果生成应急树
        self.tree = self.prefetch(obs, best)
        if a == "PROBE":
            self.probes += 1
        return best

    def prefetch(self, obs, chosen):
        # 后台线程/协程：预测 chosen 的结果类，为每个结果生成下一块候选
        # 不阻塞当前 get_action 返回；边界请求优先，预取可取消
        return SpecTree(obs, chosen, self.policy, self.outcome_head)
```

## 4. 训练配方

### 4.1 数据

- 官方 33k / 169h，LeRobot v3，30 fps，四路相机，EE base/torso，5 条英文复述（[S8][S9]）。

### 4.2 模型

- 底座：WLA-1.0-Base（6B，Apache-2.0，24GB 可微调）或开源的 \(\pi_{0.5}\)/GR00T 类底座；按许可逐个核。

- 腕部 encoder 与高位共享或独立？建议独立轻量 encoder（腕部近景分布不同），但所有头在同一 checkpoint。
- 结果预测头：2 层 Transformer/MLP，输入动作块 + 当前腕部 latent，输出 \(K\) 类结果或 latent。

- 探针分类头：轻量时序卷积/MLP，输入探针前后腕部光流/相对位移。

- 延迟/视角增广训练：8×H100 约 1–2 周（LoRA）。

- 延迟压测：单卡 + N 端口模拟，2–3 天。
- 最小可行版（不改模型）：WRG 确定性 + AWP 光流 + H=4，单卡即可；用于 W1–W2 的调试槽。

## 5. 实验协议

### 5.1 假设

- H1：腕部收益随 \(A_k\) 下降；存在任务相关 \(A^*\)。
- H2：WRG 门控优于 always-wrist / never-wrist，尤其在视角扰动/遮挡下。
- H3：SCS 预取把边界响应压到选择延迟，H=4+预取优于 H=8 同步。
- H4：AWP 在抓空/对位失败上优于“继续硬做”。
- H5：DWT 在延迟/视角扰动下优于标准训练。

### 5.2 离线/replay

- 用 held-out 演示做延迟注入：把腕部帧替换为 \(t-\Delta\)，高位/状态保持当前；测动作误差、结果预测准确率、WRG 校准。
- 视角扰动：2D 透视/裁剪/遮挡/曝光/模糊；3D 视角偏移用仿真/标定外参扰动（标注为近似）。
- 探针 replay：从演示切“抬-看”段，测光流分类器对“物体跟随/不跟随”的判别。
- 候选匹配：给定 \(o_k\)，采样 M 个候选，执行到 \(k+1\)，测 top-1 匹配是否选中实际最优候选。

### 5.3 延迟注入/系统压测

- 模拟 \(L_{network}\in\{0,20,50,100,200\}\) ms、N∈{1,3,5} 端口并发；测 p50/p95/p99 边界响应、预取命中率、回退率。
- 测 payload：四路原图 vs 高位半分辨率 + 腕部原图；目标在 7.5 Hz 下稳定。
- 测预取对边界请求的影响：预取必须可取消/低优先级；边界 p99 不能因预取变差。

### 5.4 真机调试槽

官方每天 1 个测试时段；计分与不计分共用额度（[S1][S29]）。策略：

| 阶段 | 任务 | 目的 | 判定 |
|---|---|---|---|
| W4 | T27 StackBowls | 放置/堆叠 + 腕部可见性 | 终局 +5pp 才继续 |
| W5 | T10 PlugCharger | 插入/对位 + 探针 | 探针后二次成功 >60% |
| W6 | T26 PlugInEthernet / T01 HangCup | 插入/抓空 | 回退率 <30%，无回归 |
| W7 | 计分跑 | 全 32 任务 | 总分 +3pp 目标 |

**注意**：调试槽稀缺，不做“调参器”；每个大版本最多 1 槽；每次只验证一个机制。

### 5.5 指标

| 指标 | 定义 | 用途 |
|---|---|---|
| 成功率 | 整条 episode 成功 | 主指标 |
| 步骤分 | 官方步骤分 | tie-break/诊断 |
| 终局步成功率 | 终局步骤完成 | 机制指标 |
| 首抓成功率 | 第一次抓取稳定 | 机制指标 |
| 探针后二次成功率 | 探针后下一块成功 | AWP |
| 候选匹配率 | top-1 匹配实际最优 | SCS |
| 回退率 | 匹配失败转实时推理 | 安全阀 |
| 边界响应 p50/p95/p99 | `get_action` 延迟 | 低延迟 |
| 观测年龄 \(A_k\) | 公式 | 论文核心 |
| 腕部依赖度 | 去腕部后的成功率降幅 | WRG/论文 |
| 信任校准 ECE | \(\rho\) vs 实际有用 | WRG |

### 5.6 消融

- 腕部：always-on / never / WRG / WRG+DWT；
- 探针：无 / 固定探针 / PDS 触发；
- 预取：无 / M=1/2/4/8；匹配阈值；
- H：2/4/8/16；
- 延迟：0/50/100/200 ms；
- 视角：clean / pose shift / occlusion / blur / dropout；
- 单模型审计：去结果预测头/去探针头，看增益是否来自“第二个模型”。

### 5.7 统计

- 320 trials；配对任务/种子；bootstrap 95% CI；接触密集子集单独报告。
- 不要用单任务 10 次的小样本宣称 +2pp；目标 +5pp 或机制指标显著。
- 预注册主指标/子集/停止条件，避免 p-hacking。

## 6. 论文计划

### 6.1 标题与贡献

**标题**：*The Wrist Deadline: When Close-Up Vision Arrives Too Late*

**贡献**：

1. **测量**：定义观测年龄、腕部有效反馈率、任务截止时间；在 32 个 UniBot 任务上给出“腕部收益 vs 延迟/视角扰动”的曲线，找到有用→有害的转折点。
2. **方法**：WRIST-V——WRG + AWP + SCS + PDS + DWT；不引入第二个任务模型，所有学习件在同一 checkpoint。
3. **基准**：`UniBot-Wrist`——32 任务 × 5 类腕部扰动 × 4 个延迟档；报告成功率、步骤分、观测年龄、腕部依赖度、探针率、p99。

### 6.2 基准协议

| 维度 | 设置 |
|---|---|
| 任务 | 32 个官方任务；接触密集子集约 20 个 |
| 腕部扰动 | 位姿偏移（5–20 mm / 5–15°）、遮挡（夹爪/物体）、运动模糊、曝光、掉线 |
| 延迟档 | H=2/4/8/16；注入网络延迟 0/50/100/200 ms |
| 指标 | 成功率、步骤分、终局步、首抓、探针后成功、匹配率、回退率、p99、观测年龄 |

## 8. 风险、合规与开关

## 9. 创新点清单（承接第 7 轮 I1–I13）

> 状态：押注=本轮主线；保留=沿用；升级=旧点改造；降级=保留但非主回路；砍=不做。

### I14 WRIST-V 腕部截止时间框架（新增，押注）
- 动机：固定 chunk + 远程 API 让腕部反馈老化；腕部精度收益（c 3.85→2.35mm）被延迟吃掉。
- 差异：不是“再快 20%”，而是把看/做/验证装进同一时间量子；不是 RTC/A2C2 的流式更新（API 不允许）。
- 可行性：H=4 + 预取；单 checkpoint；最小版可纯确定性。
- 资源：8×H100 1–2 周；延迟压测 2–3 天。
- 步骤：W1 测量 → W2 WRG/DWT → W3 AWP → W4 SCS → W5 真机。
- 风险：预取匹配/延迟；停止条件见 §8。

### I15 WRG 腕部可靠性门控（新增，押注）
- 动机：WARP 39.2→78.3 说明视角漂移是 first-order；Fovea 说明腕部可去掉。
- 差异：按“是否有助于成功”校准信任，而不是按图像质量分类。
- 可行性：确定性线索 + 轻量头；无额外数据。
- 风险：阈值过保守 → 回退过多；用成功率校准。

### I16 AWP 主动腕部探针（新增，押注）
- 动机：腕部装在手上，可以主动看；抓空/对位/闭合需要不同视角。
- 差异：把探针当“买信息”的动作，不是失败后的随机重试。
- 可行性：5 个探针；光流判别；演示可挖正例。
- 风险：耗时/碰撞；限速/限幅/预算。

### I17 SCS 推测式应急选择（新增，押注）
- 动机：块内不能改动作，但可以在执行时算下一块；把推理延迟藏进执行窗口。
- 差异：面向“块边界稀疏观测”的应急预取，不是每步 verifier（SV-VLA/SpecVLA）。
- 可行性：同一策略采样 + 结果预测头 + 匹配；M=2/4。
- 风险：匹配失败；回退必须便宜。

### I18 `UniBot-Wrist` 基准（新增，论文）
- 动机：没有公开的“腕部扰动 × 延迟”真机基准。
- 差异：32 任务、5 类腕部扰动、4 个延迟档；报告观测年龄与腕部依赖度。
- 可行性：replay/仿真全量 + 真机子集；赛后开源脚本。
- 风险：真机全量不现实；诚实标注。

### I1 SSG 评分步骤图（保留）
- 作用：当前步骤、终局闸门、重试/探针预算；32×5 复述匹配。

## 12. 开放问题

1. 评测端调用 `get_action` 的精确时刻：chunk 最后一步执行完立即调用，还是允许提前/延后？需要 W1 用本地 client + 真机日志测量。
2. `action_chunk_size` 是否绝对不可运行时改变？metadata 只在 handshake 读一次，但需确认评测端不会重读。
3. 网络 RTT/带宽上限；四路原图 vs 半分辨率 + 腕部原图的 p99。
4. N 的准确值；多端口并发时预取是否会被公平调度。
5. 腕部相机是否提供标定/外参？N 台机器人安装是否一致？WRG 必须在线估计。
6. 是否允许主动探针（非任务动作）？动作空间没有禁止，但需确认安全/规则边界。
7. 是否允许服务端预取/应急树？接口允许自部署计算；需在模型卡披露，确认不视为“多模型”。
8. 真实榜单何时发布；真实头部成功率；接触密集子集是否真是瓶颈。
9. 官方调试槽每天 1 次，能否在同一槽内做 A/B 多 episode？需 W1 确认。
10. 单模型边界：WRG/结果预测/探针头是否需全部写进模型卡；若审计严格，纯确定性版本能否保留大部分收益。
11. 腕部延迟增广的最佳 \(\Delta\) 范围；是否应训练多个 H 以适应不同网络。
12. 探针在透明/布料/拉链任务上的有效性；是否需要任务特定探针库。

## 13. 一句话押注

**把腕部相机当成有截止时间的证据，而不是每帧都信的输入：用 WRG 决定信不信、AWP 主动买信息、SCS 把下一块推理藏进当前块执行窗口、PDS 在看与做之间分配固定时间量子——这是 UniBot 固定 chunk + 远程 API 下，唯一同时能提高终局成功率、又不违反单模型/接口约束的低延迟路线，也是“腕部截止时间”这篇论文的核心。**
