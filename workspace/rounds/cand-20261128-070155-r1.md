### 第 6 轮灵感驱动研究记录

**灵感词**：中间件、用户共创

**继承关系**：第 5 轮 CADVS-v5（IP-493~496）以「认证的生成式执行」（CGE）把提议升级为条件流匹配 FMPP、记忆升级为可固化 LMEM-v2、人因升级为面部情感调制 FAMK，并确立定理 5~8 与 Exec_v5 ⊆ Exec_v4 ⊆ … ⊆ Exec_v29。v5 留下三个未偿结构债：(a) 提议器、记忆、价值模型、门、控制器之间是点对点耦合，缺乏统一、可审计、可版本化的接口层，导致 R59（条件接口漂移）与 R57（固化自指）无结构性抓手；(b) 人类仍被压缩成「veto + 情感传感器」，无法作为共创者参与约束、价值与测试的作者化；(c) 舰队/跨站异构只停留在第 6 轮计划，缺少可落地的证书交换与信任协商机制。本轮以「中间件 + 用户共创」统一为主题「认证中介与共创约束格」（Certified Mediation & Co-creation Lattice, CMCL），形成 CADVS-v6（IP-497~500）。本轮自律：**七硬门不增、锚点集合不变**；所有共创贡献必须挂靠七锚之一并以「只收紧」方向进入；中间件只做路由/校验/审计，不改变门的谓词。执行集嵌套升级为 Exec_CADVS-v6 ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29。

**直觉与动机**：

1. **中间件 → 把「信任边界」从隐式约定变成显式、可插拔、可审计的中介层**。v5 的失败模式大多不是门本身错，而是「谁能调用门、证书怎么流、版本怎么对」没有结构约束。引入证书中介总线 CMB：所有提议者（流、规则、遥操作、跨站同伴）只能向总线提交带类型信封的 Proposal；所有门作为总线持有的 capability 被调用，提议者无法直连门（消除绕过与提议侧 confused deputy）。信封统一携带 (anchor, claim, scope, issuer, schema_id@ver, ttl, evidence_digest, sig, provenance, revocation_ref)。总线提供三件中间件本职：**schema 注册与协商**（钉住版本，未知/不兼容版本 fail-closed，直接偿还 R59）、**来源账本与撤销**（append-only Merkle 日志，任何放宽都可追溯、可撤销）、**异构再认证**（可选双实现 G^A/G^B 独立复算，分歧即拒，部分打断 R57 自指）。关键理论点：**定理 9（中介健全性/不可绕过）**——总线不新增接受，只做过滤，故 Exec_bus(π)=Exec_gate ∩ supp(π) ∩ EnvValid ⊆ Exec_gate。中间件把「任意生成器 + 认证边界」从设计口号变成可强制的系统属性。

2. **用户共创 → 让用户成为约束/价值/测试的作者，但用格结构把「共创」限制为单调收紧**。v5 把用户当传感器，v6 把用户当作者。用户通过方向类型化约束 DSL（CDSL）作者化约束：新增谓词（AND 进入）或对既有七锚阈值做**只紧不松**的扰动 τ_i^6 = tighten_i(τ_i^5, u)，每条约束必须挂靠七锚之一（不新增锚点）。所有活跃约束 U 在安全序 ⊑ 下取 join（=交集），构成**共创约束格**。**定理 10（共创格单调性）**：只要每条约束通过方向类型检查，Exec_v6(U) 关于 U 反单调，Exec_v6(U) ⊆ Exec_v6(∅) ⊆ Exec_v5；撤销只会向 Exec_v6(∅) 回升，永不超过 v5。因此恶意/错误共创的**最坏后果是可用性损失（过度收紧），而非安全性损失**——这是与 v5「策略博弈门导致安全损失」互补的另一半保证。价值共创（PVRK）只进软评分与提议先验、以及门回归测试语料，永不直接改硬门。

3. **两者相乘 → 联邦/跨站成为中间件的自然推论，且导入他人约束在结构上安全**。跨站证书经 CMB 的 trust anchor + schema 协商交换；跨站共创约束以 join 方式导入本地格。由于 join 只收紧，**导入不可信同伴的约束不可能放宽本地执行集**（定理 10 推论），最坏是可用性下降，可用「约束配额/来源信誉/一键撤销」治理。这把 v5 遗留的舰队联邦、跨站价值/情绪异构从「待办」变成「中间件 + 格」的直接应用，且不引入新的安全假设。

**关键洞见**：v5 回答「提议可换、门不可换」；v6 回答「当提议者、门实现、用户、跨站同伴都是异构且可能不可信时，如何让『只收紧』成为可强制、可审计、可撤销的系统不变量」。七硬门 kc_evidence_forged_v5 记号原样复用；新增的只有：中介总线 CMB（路由/校验/审计，不改谓词）、共创约束格 CCL（方向类型化、join=交集）、参与式价值与红队核 PVRK（只进软评分/先验/测试语料）。执行集 Exec_v6 ⊆ Exec_v5 由「中介过滤 + 约束 join + 双实现 AND」三重保证。

**形式化目标（增量）**：
1. 证书信封与总线：Env=(cid, anchor, claim, scope, issuer, schema_id@ver, ttl, evidence_digest, sig, provenance, revocation_ref)；总线状态机 Mediate(Proposal, Gates, U, Attest)。
2. 方向类型化约束 DSL：CDSL 文法 + 类型规则「u : Narrow(anchor_i)」；tighten 算子对下界门取 max、上界门取 min；join ⊔ = 交集。
3. 共创格：偏序 u1 ⊑ u2 ⇔ Exec(u1) ⊇ Exec(u2)；活跃集 U 与撤销算子 Rev。
4. 双实现再认证：Attest(x)=1[G^A(x)=G^B(x)=1]（高 stakes 层启用，AND，fail-closed）。
5. 定理 9（中介健全性/不可绕过）、定理 10（共创格单调与撤销有界）、定理 11（双实现自指界）、定理 12（来源/撤销完备与 schema 漂移 fail-closed）；引理 45（CDSL 收窄性可判定）。
6. EFA-v6：Exec_CADVS-v6 = {x ∈ Exec_CADVS-v5 : EnvValid(x) ∧ ∧_{u∈U} u(x)=1 ∧ Attest(x)=1} ⊆ Exec_CADVS-v5。

**本轮最大风险**：**中间件信任集中与单调性校验器 TCB**——「用户只能收紧」这一核心安全论证最终寄托在 CMB 的 schema 注册表、capability 分发与 CDSL 收窄性校验器上；一旦该 TCB 被攻破或 DSL 语义存在漏洞（如逃逸到非受限片段），共创即可被用作「合法外观下的放宽」或总线成为单点故障，双实现与形式化 DSL 只能缩小而无法消除这一根信任。

## 2. 关键算法骨架

### IP-497 CMB：证书中介总线（准入/10 Hz 时域，不在 1 kHz 环）

```python
@dataclass
class CertificateMediationBus:
    """CMB-v6：证书中介总线。只路由/校验/审计，不改门谓词。
    定理 9：总线不新增接受，只做过滤——提议者无法绕过门。"""
    schema_registry: SchemaRegistry
    trust_anchors: dict
    ledger: MerkleLedger
    caps: CapabilityTable          # 门只由总线持有 capability
    attest: AttestationTier | None # 可选双实现 G^A/G^B（AND）

    def submit(self, proposal: Proposal, principal: Principal) -> Env | Reject:
        if not self.caps.allow(principal, 'propose'):
            return Reject('NO_CAP')                 # 提议者不能持有门 capability
        env = proposal.envelope
        if not self.schema_registry.compatible(env.schema_id, env.schema_ver):
            return Reject('SCHEMA_MISMATCH')        # R59：未知/不兼容版本 fail-closed
        if not verify_sig(env, self.trust_anchors):
            return Reject('BAD_SIG')
        if env.revocation_ref in self.ledger.revoked:
            return Reject('REVOKED')
        if env.anchor not in SEVEN_ANCHORS:
            return Reject('NO_ANCHOR')              # 共创/证书必须挂靠七锚
        self.ledger.append(env)                     # append-only 来源账本
        return env

    def mediate(self, env: Env, x: Trajectory, c: Context, U: ActiveSet):
        # 1) v5 七硬门（经 capability；提议者不可直连）
        if not self.gates.v5_all(x, c):
            return Reject('GATE')
        # 2) 共创约束格（只紧；join 已预计算）
        if not all(u(x) for u in U):
            return Reject('COCREATE')
        # 3) 可选双实现再认证（分歧即拒）
        if self.attest is not None and not self.attest.agree(x, c):
            return Reject('ATTEST')
        return Accept(x)

    def import_peer_constraints(self, peer_envs, peer_anchor) -> ActiveSet:
        """跨站导入：只允许 join（交集），故不可放宽本地执行集（定理 10 推论）"""
        incoming = [u for u in peer_envs if verify_sig(u, peer_anchor)]
        return self.local_U.join(incoming)          # 只紧
```

### IP-498 CCL：共创约束格（方向类型化，join=交集）

```python
@dataclass
class CoCreationConstraintLattice:
    """CCL-v6：用户共创约束格。方向类型化，join=交集，撤销有界。
    定理 10：恶意/错误共创最坏只损失可用性，不损失安全性。"""
    checker: NarrowingTypeChecker
    ledger: MerkleLedger

    def admit(self, u: UserConstraint, principal: Principal) -> Constraint | Reject:
        if u.anchor not in SEVEN_ANCHORS:
            return Reject('NO_ANCHOR')              # 不新增锚点
        if not self.checker.proves_narrowing(u):     # 引理 45：仅 CDSL_core 可判定
            return Reject('NOT_NARROWING')           # 任意代码/逃逸片段一律拒绝
        if not verify_sig(u, principal):
            return Reject('BAD_SIG')
        self.ledger.append(u)
        return u

    def join(self, U: list[Constraint]) -> ActiveSet:
        # 安全序 ⊑：u1 ⊑ u2 ⇔ Exec(u1) ⊇ Exec(u2)；join = 交集 = 更紧者
        return ActiveSet(tuple(sorted(U, key=tightness)), intersect=True)

    def tighten(self, tau5: float, u: Constraint, anchor: str) -> float:
        # 下界门取 max，上界门取 min；只紧不松（τ^6 相对 τ^5）
        return max(tau5, u.lower) if is_lower_bound(anchor) else min(tau5, u.upper)

    def revoke(self, u: Constraint, principal: Principal) -> ActiveSet:
        # 撤销需签名；执行集向 Exec_v6(∅) 单调回升，永不越过 v5
        self.ledger.append_revocation(u, principal)
        return self.join([v for v in self.active if v != u])
```

```python
    定理 12：(i) 每个被接受的 x 都有可验证来源链，终止于签名主体；
    (ii) 任何约束移除需签名撤销并写入账本 ⇒ 无匿名放宽、可审计、可追责；
    (iii) schema 不匹配/未知版本一律拒绝 ⇒ 版本漂移不能静默改变语义（R59）。
    证明：信封字段完整性 + 账本 append-only + 总线校验顺序。∎
    """
    return "Proven"
```

### IP-500 EFA-v6：总线中介 + 共创格 + 双实现认证

```python
@dataclass
class CertificateMediationAssemblerV6:
    """EFA-v6：七硬门不变（capability 隔离）+ 共创约束 join + 可选双实现 AND"""
    bus: CertificateMediationBus
    ccl: CoCreationConstraintLattice
    pvrk: ParticipatoryValueRedteamKernel
    v5: EvidenceForgingAssemblerV5

    def select(self, x0_state, t_now, rule_id, context, principal):
        s_emo = self.v5.famk.observe(context.face, t_now)
        gamma = self.v5.famk.gamma(s_emo)                 # 全 1.0 = 精确退化 v4 静态
        c = build_ctx(context, s_emo, self.v5.lmem)       # 含 Top-k 记忆 token
        U = self.ccl.join(self.ccl.active(principal))     # 只紧的活跃约束
        cands = self.v5.fmpp.propose(c, self.v5.fmpp.K)   # K=8，异步准入
        envs = [self.bus.submit(Proposal(x, c, anchor='coverage'), principal)
                for x in cands]
        envs = [e for e in envs if not isinstance(e, Reject)]
        if not envs:
            return self.v5._fallback_rule_proposal(gamma)  # fail-closed 回退规则提议
        surv = [e for e in envs if self.bus.gates.cheap(e.x, gamma)]
        if not surv:
            return self.v5._fallback_rule_proposal(gamma)
        # 总线 mediate：v5 七门 + U + Attest，逐层产证书信封
        ok = [e for e in surv if not isinstance(self.bus.mediate(e, e.x, c, U), Reject)]
        if not ok:
            return False, None, 'ALL_CANDIDATES_REJECTED'
        best = max(ok, key=lambda e: certified_margin(e.x))  # 通过者取边际最大
        return True, best.x, 'FORGED_CMCL'

    def ecs_v6(self, n_flow, s_emo, delta_margin_ab=None) -> float:
        eta_att = 1.0 if delta_margin_ab is None else sigmoid(delta_margin_ab)
        return self.v5.ecs_v5(n_flow=n_flow, s_emo=s_emo) * eta_att
```

| PVRK 回归 | O(\|corpus\|·门) | O(\|corpus\|) | 离线 | 分钟级，固化前 |

**通信开销**：证书信封 ~0.5 KB/候选（签名 + 来源哈希）；跨站只交换信封与约束摘要（~2 KB/站）；来源账本 Merkle 根低频同步；人脸特征/原始图像永不出端（沿用 v5）。

**实时性说明**：CMB/CCL/Attest 全部在准入（10 Hz 预览）时域，控制环只消费预计算阈值 τ^6 与缓存证书；总线不进入 1 kHz 环，故 v5 的 P99 0.55 ms 不被侵蚀。

## 4. 正确性论证（增量更新）

### 引理 45（CDSL 收窄性可判定）

**陈述**：在 CDSL_core（阈值/区间谓词、有界算术、单调阈值扰动，无循环/递归/无界算术）上，性质「u 只收紧」可在区间抽象域上判定；对任意用户代码该性质不可判定（Rice 定理）。**工程结论**：只接受 CDSL_core 的约束，拒绝一切「自定义代码/逃生口」，以免单调性论证被绕过。∎

### 定理 9（中介健全性/不可绕过）

**陈述**：设总线只转发 EnvValid 且不修改门谓词，则对任意提议分布 π，`Exec_bus(π) = Exec_gate ∩ supp(π) ∩ EnvValid ⊆ Exec_gate`。**证明**：接受条件被总线分解为「信封合法 ∧ 门通过」；总线不持有任何新增接受分支，故只做过滤。∎ **推论**：提议者即使被攻破，也只能降低通过率，不能把执行集扩出 `Exec_gate`；任何放宽必须由门所有者经 capability 修改并写入账本。

### 定理 10（共创格单调性与撤销有界）

**陈述**：若每条 u 通过 `Narrow` 类型检查，则 (i) U1 ⊆ U2 ⇒ Exec_v6(U2) ⊆ Exec_v6(U1)；(ii) Exec_v6(U) ⊆ Exec_v6(∅) ⊆ Exec_v5；(iii) Rev 只使执行集向 Exec_v6(∅) 单调回升，封顶于 v5；(iv) 跨站约束 join 导入不可放宽本地执行集。**证明**：(i) 交集随集合增大而缩小 + 阈值 `tighten` 单调；(ii) 由 (i) 取 U=∅ 与 v5 门不变；(iii) 撤销是集合删除，按 (i) 反向单调且有上界；(iv) join 只做交集，与来源无关。∎ **含义**：恶意/错误共创的最坏后果是可用性损失（过度收紧），而非安全性损失——与 v5「策略博弈门导致安全损失」互补。

### 定理 11（双实现再认证与自指界）

**陈述**：设 G^A、G^B 独立且规格正确，p_A、p_B 为各自放过非合规 x 的概率，则 `P(G^A=G^B=1 | x 非合规) ≤ p_A·p_B`；分歧即拒（fail-closed）。**证明**：独立事件乘法 + AND 接受条件。∎ **诚实边界**：相关规格错误（共享 spec bug、同源训练数据、同一团队）不被覆盖，双实现可能同错；因此该界只在「独立实现 + 规格正确」假设下成立，且不能替代人工审计。

### 定理 12（来源/撤销完备与 schema 漂移 fail-closed）

**陈述**：(i) 每个被接受的 x 都有可验证来源链，终止于签名主体；(ii) 任何约束移除需签名撤销并写入账本 ⇒ 无匿名放宽、可审计、可追责；(iii) schema 不匹配/未知版本一律拒绝 ⇒ 版本漂移不能静默改变语义（偿还 R59）。**证明**：信封字段完整性 + 账本 append-only + 总线校验顺序（先 schema/签名/撤销，再门/约束/认证）。∎

### 定理 v6（中介-共创执行集三重收缩，总装）

**陈述**：在 v5 假设 (B1)~(B7) 及新增 (B8)「CDSL_core 收窄性检查可靠」下：
(i) Exec_CADVS-v6 ⊆ Exec_CADVS-v5（严格：EnvValid/Attest/非空 U 非恒真）⊆ … ⊆ Exec_v29；
(ii) 中介健全：执行边界与提议者无关，提议者不可绕过门（定理 9）；
(iii) 共创单调：U 只收紧，撤销有界，跨站导入只紧（定理 10）；
(iv) 双实现：分歧即拒，自指博弈概率在独立+规格正确下 ≤ p_A·p_B（定理 11）；
(v) 来源/撤销完备，schema 漂移 fail-closed（定理 12）；
(vi) 七锚完备性保持：CMB 要求 anchor ∈ 七锚，CCL 不新增锚点，PVRK 只进软评分/先验/测试语料。

**证明**：(i) 由「中介过滤 + 约束 join + 双实现 AND」三重交集；(ii)~(v) 分别由定理 9/10/11/12；(vi) 由 anchor 约束 + 类型检查。∎

**诚实声明**：(B8) 把安全论证的根信任压到 CMB 与 CDSL 校验器这一 TCB 上——若 TCB 被攻破或 DSL 有语义漏洞，定理 10 不成立；(ii) 双实现只在「独立 + 规格正确」下有效，相关规格错误无界；(iii) 共创的过度收紧会造成可用性/公平性问题（多数人价值锁死少数人），只能靠配额与撤销治理，无结构性消除；(iv) 加性价值假设 (B4) 继承自 v4，仍未解决。

## 7. 本轮最大风险（最终确认）

**一句话**：**中间件信任集中与单调性校验器 TCB**——「用户只能收紧」这一核心安全论证最终寄托在 CMB 的 schema 注册表、capability 分发与 CDSL 收窄性校验器上；一旦该 TCB 被攻破或 DSL 语义存在漏洞（如逃逸到非受限片段），共创即可被用作「合法外观下的放宽」或总线成为单点故障，双实现与形式化 DSL 只能缩小而无法消除这一根信任。
