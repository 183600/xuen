## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（场景泛化 → 评测轴是开卷的，但多数队伍把它当成纯数据问题）**
直觉：五轴里「位置变化 / 背景差异 / 干扰物」都是场景变量 S 的偏移。常规反应是加增广、加数据。但这里藏着一个更便宜的问题：**动作坐标系决定了场景偏移是「输入的小变化」还是「输出的大变化」**。物体平移 10cm，相对 EE 动作只需改「当前 EE→物体」的相对位姿估计；绝对关节目标却要重新学一个完全不同的关节构型。第 2 轮把「场景泛化」全部压在 I1 增广 + I2 数据上，缺了「表示」这一层。核心反直觉点：**场景泛化的第一性原理不是「见过更多场景」，而是「把场景变化搬到输入空间，而不是让输出空间去记忆它」。**

**灵感 2（关节空间控制 → 关节空间是执行空间，不是泛化空间）**
直觉：看到「关节空间控制」很容易直接想「那就输出关节角」。但官方预训练头原生输出相对 EE（F21），官方部署也是「相对 EE 预测 → SE3 compose → WBC/IK → 关节执行」（F22）。这说明关节空间的正确定位不是「预测空间」，而是**可行性空间**：关节限位、奇异、速度/加速度、冗余零空间、腰腿协调都只在这里能显式约束。提交接口允许我们二选一（F20）：选 ee 是把 IK 交给评测端（黑箱），选 joint 是自己拥有 IK（可加约束、可平滑、可做全身）。核心反直觉点：**关节空间控制的价值不是「直接输出关节角」，而是「给任务空间动作提供一个物理可行的投影器与平滑器」；把关节空间当预测空间是范畴错误。**

**两者统一（并修正第 2 轮的数据引擎论）**：第 2 轮说「中期胜负手在数据引擎」。本轮补一层：数据引擎的标签活在一个动作坐标系里；坐标系不具场景等变性，更多数据只是记住更多绝对构型。正确顺序是：**(1) 选场景等变的动作参数化 → (2) 用关节空间可行性做增广标签的物理门禁 → (3) 再放数据量**。一句话：**先正坐标系，再放数据量。**

## 2. 严谨定义（把直觉写成可检验的命题）

**定义 1（场景变量与评测分布）**：S = (物体位姿、干扰物集合、桌面背景/光照、未见物品外观、人手干预)。评测对每任务抽 10 个 S，五轴各 2 次（F23）。策略 π(a|o,l) 在动作空间 A 上输出。

**定义 2（动作表示的场景等变性）**：设 g∈SE(3) 作用于场景（物体+桌面），期望任务空间轨迹变换为 T_t ↦ gT_t。相对 EE 表示 r_t = T_t^{-1}T_{t+1} 满足 (gT_t)^{-1}(gT_{t+1}) = T_t^{-1}T_{t+1} = r_t，即**轨迹形状对共同刚体变换不变**；绝对关节表示 q_t = IK(T_t) 一般有 IK(gT_t) ≠ q_t。注意边界：机器人基座不动时，首步仍需从真实 T_0 追到 gT_1，故不变性只对「追上后的稳态段」成立——这正好是闭环视觉伺服要解决的问题。结论：相对 EE 把场景偏移压缩成「相对位姿估计」问题，绝对关节把它放大成「全链重解」问题。

**定义 3（关节可行域与场景泛化包络）**：给定任务示教轨迹 τ 与平移 g，定义 F(g)=1 当且仅当存在光滑关节轨迹 q_t 满足 FK(q_t)=gT_t、q_min≤q_t≤q_max、|q_{t+1}-q_t|≤Δq_max、无自碰撞/桌面碰撞、且 σ_min(J(q_t))≥σ0。集合 G_τ={g:F(g)=1} 是该示教在位置轴上的**可行平移包络**。它可以用 IK 离线估计，是 I1 位置轴剂量的物理上界，也是 I11 增广的筛选器。

**定义 4（双空间动作接口）**：策略内部输出相对 EE chunk r_{0:H-1}；解析器 R 先 compose 成绝对 EE T*_k，再解约束 QP 得关节 chunk q*_k。参赛实体仍是一个 PolicyService；R 是确定性经典控制（非第二个学习模型）。形式化：
q* = argmin_q ||q-q_t||_W² + λ_s||q-2q_{t-1}+q_{t-2}||² + λ_n||(I-J⁺J)(q-q_posture)||²
s.t. FK(q)=T*, q_min≤q≤q_max, |q-q_t|≤Δq_max, σ_min(J(q))≥σ0。
（工程上用阻尼最小二乘 + 零空间投影 + 限幅实现。）

## 3. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

- **Q9（场景等变动作表示）**：在等数据、等模型下，相对 EE / 物体系 / 绝对关节三种动作表示，哪一种在位置轴上的泛化缺口最小？假设：相对 EE > 绝对关节；物体系在大位移/未见物品上更优，但依赖物体位姿估计。如何用 L0 离线实验分离「表示」与「数据」的贡献？
- **Q10（关节可行域作为增广 oracle）**：用 IK 可行域筛选场景平移后的示教，能否比纯像素增广更有效地提升位置轴成功率？各任务的 G_τ 包络有多大，是否足以覆盖官方位置扰动范围？
- **Q11（控制空间 A/B 与全身门控）**：同一相对 EE 检查点，joint 模式（自有 IK/QP）与 ee 模式（评测端 IK）在成功率、动作健康度、延迟上谁更优？腰/腿冗余在什么边界条件下扩展工作空间而不伤稳定性？

## 4. 设计原则（新增 PR6–PR7，PR1–PR5 保留）

- **PR6 场景等变律**：任何计分场景变换 g，训练对必须一致变换：o' = g·o 且 a' = g·a（在 g 能自然作用的表示里）。若动作表示无法表达 g，就用解析器/可行性过滤，**绝不在不一致的 (o', a) 上训练**。与 PR5（数据杠杆律）互补：PR5 管「这条数据教什么」，PR6 管「这条数据在什么坐标系里一致」。
- **PR7 泛化空间与执行空间分离律**：在足够表达任务的最场景不变空间里预测；在物理约束最完整的关节空间里解析执行。不要把两者混为一谈。与 PR1（决策）互补：PR1 管「何时做什么」，PR7 管「在哪个空间做」。
- PR1–PR5 保留（第 1–2 轮）。

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2）

> 检索日期：2026-11-26（R1）、2026-11-27（R2）、2026-11-27（R3）；来源见 §6。承接 v1.1：新增 I10/I11，深化 I1/I3/I6/I9，I2/I4/I5/I8 维持并小幅修订。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I10 双空间动作接口：场景等变预测 + 关节可行解析（新）★★★★★
- **动机**：五轴中的位置轴直接考验「动作坐标系是否随场景平移而稳定」；官方预训练头是相对 EE（F21），提交接口允许 joint/ee 二选一（F20）。选 ee 把 IK 交给评测端黑箱；选 joint 则自己拥有 IK，可显式加限位、平滑、奇异规避、零空间姿态与全身协调。
- **与现有方案差异**：官方 WBC 已做「相对 EE→绝对 EE→IK」，但 IK 在机器人客户端；本点把解析器搬进 PolicyService，并把它作为**场景条件化**组件：只在接近工作空间边界/奇异时启用腰腿冗余，平时保持标称姿态。不是新模型，是动作解码层的重设计。
- **技术可行性**：高。7-DoF 臂阻尼最小二乘 IK + 零空间投影 + 限幅，单步 <1ms（CPU）；G1 关节序/限位可查（F26）。风险是提交端 conformance。
- **所需资源**：1 人周工程 + CPU；无需额外 GPU；与 I6 共用部署服务。
- **落地步骤**：①写死 G1 29-DoF 左/右臂关节序与限位；②相对 EE→绝对 EE compose（复用官方 `_compose_ee9` 逻辑）；③阻尼 IK + 零空间姿态 + 速度/加速度限幅；④奇异度 σ_min(J) 监控与回退；⑤全身门控（腰 3 DoF 先、base 后）；⑥joint/ee 双 wrapper；⑦单任务 conformance test。
- **风险**：提交端关节序/符号/限位不同（缓解：先发零动作+小幅正弦做 conformance，观测 `observation.state.left_arm` 回读）；评测端控制器自带平滑/限幅（缓解：A/B 量化差异，不假设）；pivot 语义不明（缓解：第一版不依赖 pivot，只动臂；腰腿作为可选开关）。

### I11 场景等变示教重投影 SEDR（新）★★★★★
- **动机**：第 2 轮 I1 的位置轴是像素级重拼接，物理可行性无保证；纯像素增广还会教错不变性（图变了、动作标签没变）。位置轴需要一个**物理一致**的动作标签增广。
- **机制**：①从示教恢复绝对 EE 轨迹 T_t（相对动作 + 初始 EE 状态）；②对场景施加平移 g（物体+桌面一起移，或按任务只移相关物体）；③得到期望轨迹 gT_t；④用 IK 投影到关节空间，检查限位/速度/奇异/碰撞；⑤保留可行段，重算相对 EE 标签 r'_t=(gT_t)^{-1}(gT_{t+1})（稳态段不变，首步追及段改变）；⑥像素侧同步渲染/搬移物体，形成一致的 (o', a')。
- **与现有方案差异**：常规增广只动图不动标签；SEDR 动标签并用关节可行性做门禁。它把「关节空间」当**物理 oracle**，不要求部署时选 joint 模式——离线即可用，风险与 I10 解耦。
- **技术可行性**：中-高。依赖每任务物体位姿/掩码与 IK；单物体任务可直接做，双手/多物体任务需一致变换全部任务相关物体。
- **所需资源**：1×GPU 做渲染/分割 + CPU IK；数据工程 2 人周；每任务 G_τ 包络估计约 1 GPU 日。
- **落地步骤**：①3 个单物体任务（HangCup/StoreCups/PlacePhotoFrame）试点；②估计 G_τ；③生成 SEDR 数据；④L0 消融（像素增广 vs SEDR vs 两者）；⑤扩展到双手任务（一致变换）；⑥把 G_τ 反馈给 I1 剂量。
- **风险**：多物体任务全局平移不成立（缓解：只对单物体/整体布局任务启用，或按物体分别变换并检查双手相对几何）；IK 失败率高（缓解：只保留可行段，报告可行率作为任务难度指标）；渲染与真实分布差距（缓解：与 I1 的背景/干扰物增广叠加，不单独使用）。

### I1 v3 考纲校准五轴增广引擎 ★★★★★

### 1.1 双空间解析器（I10）

```python
# 输入：相对 EE chunk (H,6) [xyz, rotvec] in current EE frame；当前关节 q_t、EE 位姿 T_t、腰 q_w
# 输出：joint chunk (H,7) 或 ee chunk (H,6)
def resolve_chunk(rel_ee, T_cur, q_cur, q_prev, q_posture, waist=None):
    out = []
    q_prev2 = q_prev
    for k in range(H):
        T_target = compose_se3(T_cur, rel_ee[k])          # 官方 _compose_ee9 同义
        q_ref = q_cur if k == 0 else out[-1]
        q_star = qp_ik(T_target, q_ref, q_prev2,
                       q_min=Q_MIN, q_max=Q_MAX,
                       dq_max=DQ_MAX, sigma_min=SIGMA_MIN,
                       posture=q_posture, waist=waist)   # 阻尼最小二乘 + 零空间
        out.append(q_star)
        q_prev2 = q_ref
    return np.stack(out)                                  # (H,7)

def qp_ik(T_target, q_ref, q_prev, q_min, q_max, dq_max, sigma_min, posture, waist=None):
    q = q_ref.copy()
    for _ in range(ITER):                                 # 3–5 次阻尼迭代
        T = fk(q)                                         # 含 waist 时 q 为臂+腰
        e = se3_log(T_target @ inv(T))                    # 6 维误差
        J = jacobian(q)
        lam = LAM_SING if sigma_min(J) < sigma_min else LAM
        dq = J.T @ np.linalg.solve(J @ J.T + lam**2 * np.eye(6), e)
        dq_null = nullspace_project(J, posture - q)       # (I - J^+ J)
        q = clamp(q + dq + ALPHA_NULL * dq_null, q_min, q_max)
        q = clamp(q, q_ref - dq_max, q_ref + dq_max)
        if np.linalg.norm(e) < EPS: break
    return q
```

### 1.2 SEDR 场景等变重投影（I11）

```python
def sedr_augment(episode, g, ik_solver, scene_objects, render=True):
    # 1) 恢复绝对 EE 轨迹
    T_abs = compose_trajectory(episode.ee0, episode.rel_ee)       # (T,4,4)
    # 2) 场景平移：只对任务相关物体一致变换（单物体任务 g 作用于全任务；双手任务需一致）
    T_abs_aug = apply_scene_transform(T_abs, g, scene_objects)
    # 3) IK 投影 + 物理可行性过滤
    q_aug, feasible = [], []
    for t, T in enumerate(T_abs_aug):
        q, ok = ik_solver.solve(T, q_ref=q_aug[-1] if q_aug else episode.q0[t])
        if not ok: break
        q_aug.append(q); feasible.append(ok)
    if len(q_aug) < MIN_SEG: return None                          # 丢弃
    # 4) 重算相对 EE 标签（稳态段不变；首步追及段改变）
    rel_aug = [inv(T_abs_aug[t]) @ T_abs_aug[t+1] for t in range(len(q_aug)-1)]
    # 5) 同步像素：把物体/桌面按 g 搬移或渲染；与 (rel_aug, q_aug) 配对
    obs_aug = render_scene(episode.obs, g, scene_objects) if render else None
    return {"obs": obs_aug, "rel_ee": rel_aug, "joint": q_aug,
            "feasible": True, "delta": g}

def estimate_envelope(episode, ik_solver, deltas):
    ok = []
    for g in deltas:                                              # 位置轴采样
        ok.append(sedr_augment(episode, g, ik_solver, ..., render=False) is not None)
    return {"G_task": deltas[ok], "feasible_rate": mean(ok)}      # 反馈给 I1 剂量
```

## 2. 形式化推导（为什么相对 EE 更抗位置轴）

设场景平移 g∈SE(3) 作用于物体与桌面，期望 EE 轨迹 T_t ↦ gT_t。相对动作 r_t = T_t^{-1}T_{t+1}。则

r'_t = (gT_t)^{-1}(gT_{t+1}) = T_t^{-1}g^{-1}gT_{t+1} = T_t^{-1}T_{t+1} = r_t.

故相对 EE 动作对**共同**刚体变换严格不变；变化的只有「从真实初始 EE 追到 gT_0」的首段。绝对关节 q_t=IK(T_t) 无此性质：IK(gT_t) 是 g 的非线性函数，且可能跨过关节限位/奇异分支。物体系动作 r^obj_t = T_obj(t)^{-1}T_t 对物体自身运动也不变，但需要 T_obj 估计，误差会直接进入动作；相对 EE 不需要物体位姿，只需要「当前 EE 相对目标」的视觉估计，是**无需物体模型的等变表示**。这解释了为什么 I10 以相对 EE 为预测空间、以关节空间为解析空间，而不是直接预测关节。

**可行包络与剂量**：对每任务示教 τ，采样平移 g，定义可行率 ρ(δ)=P_{g:|g|=δ}[F(g)=1]。位置轴增广剂量应满足 δ ≤ δ*(ρ=0.9)，即 90% 的平移仍可被 IK 可行投影。δ* 可由示教离线估计，直接替代 I1 的「位置重拼接」经验参数。
