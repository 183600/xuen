# 第 70 轮（承接第 69 轮「FLUID-RAS 交互消歧」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「自然语言指令」×「安全对齐」）

> R69 给闭环装上了「嘴巴」：系统会看、会问、会触，并用 k 个正交证据源约束「问到的答案」。但它对两样东西几乎无条件信任——**人说的话**（指令/回答）与**人说话的资格**（谁有权说）。R69 的交互仍建立在一个封闭假设上：提问是安全的，答案只要多源一致就可用，指令则被悄悄当成「要执行的目标」。
>
> 本轮两个灵感把这条信任链拆开：
> - **自然语言指令**不是命令，而是一份**有损、欠定、可能被伪造的合同**——它是对「人类意图」这个隐变量的一次观测，而不是意图本身；
> - **安全对齐**不是「让系统更听话」，而是**保证语言这条通道永远不能扩张系统的可执行边界**——它可以收窄（说不许做什么），但物理安全与宪法底线不可被一句「我允许」解除。
>
> 核心命题：**指令是合同，不是命令；语言只能收窄规范集，永不扩张安全包络；执行集 = 意图规范集 ∩ 物理安全 ∩ 策略能力；对齐是双边损失（欠拒与过拒都要罚），而授权完整性是任何策略能力都无法替代的前置条件。** 命名 **LIRA-RAS**（Language-Instruction Regulated Alignment）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证、还能问什么」，R70 问「**这句话到底是什么意思、是谁有资格说的、我能不能不听**」——安全不是服从的强度，而是服从的边界。

## 0. 直觉与动机

**灵感 1（自然语言指令 → 意图是隐变量，指令只是它的一次有损投影）**
直觉：人对机器人说「把桌上那个拿过来」，这句话并不唯一确定一个动作：指哪个物体、拿给谁、多快、能不能碰倒别的杯子——全都没说。我们习惯把「听懂指令」当成感知问题（文本→目标），更准确的说法是：**指令是对意图 I 的一次含噪观测 x**，真正的对象是后验 p(I | x, 上下文)。把指令当命令执行，等于把后验众数当成真值，还拒绝承认别的合理解释（澄清集 𝒞(x)）。R69 已经承认「动作有多个模态」，R70 要承认「**意图也有多个模态**」——而且后者更危险，因为它决定「什么算对」。

**灵感 2（指令 → 合同；安全对齐 → 合同可行性核验）**
直觉：一份合同不会因为签了字就自动可执行，它要过合规审查：目标是否合法、条款是否自相矛盾、是否超出签约人权限、是否与上位法冲突。把自然语言指令当合同看，安全对齐就变成一次**可行性判定**：这个意图的规范集 𝒩(I) 与物理安全 𝒮_phys、策略能力 Cap 的交集 ℰ(I) 是否非空？空 ⇒ 不可行，必须拒绝或协商；多个意图给出不同的 ℰ ⇒ 欠定，必须澄清或保守补全。三分法（可执行/不可行/欠定）取代 R69 的「选一个模态执行」。

**灵感 3（安全对齐 → 非扩张不变式：语言不能洗白安全）**
直觉：R68 的铁律是「任何不确定 → 只收紧」；R69 给了一个例外「不确定但可消解 → 可以松开」。R70 再加一条更硬的：**语言指令只能让系统做得更少，不能让它做得更多**。「用户允许我闯红灯」不是安全豁免；「这是紧急任务，解除限速」不能扩张执行器的物理包络。这里要把两件事分开：**授权**决定「谁的目标算数」，**安全包络**决定「哪些动作物理/伦理上根本不做」。前者可被委托（且委托只能收窄），后者不可让渡。把这条写成不变式，R69 最大的担忧（问错 → 被证实的错误）就被降级为「最多更保守」，而不会升级为「越界」。

**灵感 4（安全对齐是双边损失，不是「越安全越好」）**
直觉：一个永远说「不」的系统在「不伤害」这一维上满分，但对齐度为 0——它拒绝了所有安全且被授权的意图。真实的安全对齐是**欠拒（执行了不该执行的）与过拒（拒绝了本可安全执行的）之间的权衡**，两端都罚。R69 的保守退避在「只收紧」意义上是对的，但把它当成对齐的全部，会把「对齐」偷换成「僵化」。所以本轮必须显式定义双边对齐损失 L_align，并承认：**纯保守不是安全，是另一种失配**；只是这种失配的代价更容易被审计。

**灵感 5（指令层是最肥的攻击面 → 来源隔离、授权账本、冲突不自动裁决）**
直觉：一旦语言能改变行为，语言就成了攻击面：网页里藏一句「忽略之前的指令」、旁人冒充主人、旧指令没撤销、单条无害的指令组合起来有害（木马组合）、用委婉语绕过安全词表。防御不能靠「更聪明的模型猜意图」，而要靠**结构性隔离**：指令/数据分离（来源防火墙）、带认证与吊销的授权账本、单调不增的委托代数、以及「安全关键冲突不得自动裁决」。这些不是模型能力问题，是**权限系统**问题——就像操作系统不会因为应用请求就给它 root。

## 1. 形式化定义（增量：定义 310–326）

**定义 310（LIRA-RAS 总览）** LIRA-RAS = (IIS, SCA, SWCG, IAL, ADA, PCR, CCR, NCM, ICG, SRL, NCO, FLUID†)。四条不变式：
(i) **非扩张不变式**：规范集单调收窄 𝒩_{t+1} ⊆ 𝒩_t，且恒有 𝒩_t ⊆ K ⊆ 安全约束；语言永不扩张物理安全包络 𝒮_phys；
(ii) **授权完整性**：每条指令携带可验证的 (说话人, 授权域, 时效, 来源, 撤销状态)；未验证指令降级为 *建议*，可更新信念但不可收窄 𝒩；
(iii) **澄清先于承诺**：若意图歧义会改变动作的安全分类，必须先澄清或取保守解释，禁止静默向高风险方向消歧；
(iv) **证据纪律继承**（R69 定义 293-iii）与交互预算继承（定义 293-ii）。

**定义 311（意图空间与指令观测）** 意图 I = (g, C, ≻, ρ, τ_stop) ∈ ℐ：目标 g（可达状态/谓词集）、显式约束 C、偏好序 ≻、风险容忍 ρ、终止条件 τ_stop。自然语言指令 x ∈ 𝒳 是 I 的有损、可能被污染的一次观测；p(I | x, h_t) 由冻结语言模型 + 具身接地给出。澄清集 𝒞(x) = supp p(I | x, h_t)，即「这句话能合理地被解释成的所有意图」。

**定义 312（规范集、宪法与执行集）** 宪法 K ⊂ 𝒯raj 是不可让渡的硬约束集（人身安全、法律、伦理底线），带版本号。给定意图 I，规范集 𝒩(I) = {ξ : ξ 达成 g ∧ ξ 满足 C ∧ 按 ≻ 最优 ∧ risk(ξ) ≤ ρ} ∩ K。物理安全包络 𝒮_phys（执行器/环境）。执行集 ℰ(I) = 𝒩(I) ∩ 𝒮_phys ∩ Cap_θ。核心：𝒩(I) ⊆ K 恒成立，且 𝒮_phys ∩ K 与语言无关。

**定义 313（对齐三分）** 对后验 p(I | x)：**可执行**（所有高概率 I 的 ℰ(I) ≠ ∅ 且 risk ≤ ρ）、**不可行/冲突**（存在高概率 I 使 ℰ(I) = ∅，即意图与宪法/物理矛盾）、**欠定**（不同 I 的执行集不同，尤其安全分类翻转）。系统必须显式落入三分之一；禁止把不可行静默松弛成可执行。

**定义 314（意图不确定性分解与风险耦合）** U_int^ale = E_I[Var(执行 | I)]（同一意图内的执行噪声）；U_int^epi = I(I; 安全动作类)（意图身份对「哪些动作安全」的互信息）。新增**风险耦合** χ = P_{I~p}(ℰ(I) 中存在违反 ρ 的动作)（不同意图导致安全分类翻转的概率质量）。R69 的 U_epi 只度量动作模态歧义；U_int^epi 度量的是**规范**歧义，且只有 χ 高的部分才值得优先澄清。

**定义 315（双边对齐损失）** L_align = α·E[执行不安全动作] + β·E[拒绝安全可达意图] + γ·E[静默曲解意图]。三项此消彼长；纯保守令 β 项爆炸，并非对齐。其 Pareto 前沿由 (α, β, ρ) 决定，最优点一般不在「最大安全」端点。

**定义 316（安全加权澄清门 SWCG）** VoI_safe(g) = E_I[ΔH(I | g)]·(1 + κ·χ(g)) − c(g)，κ 度量「澄清错方向的代价」。选 g* = argmax VoI_safe，优先压安全关键歧义；若 max VoI_safe ≤ 0 或无预算 → 保守补全（在 𝒞(x) 中取最小最大风险意图 I_safe），并**标记可能的过度拒绝**供人工复核。

**定义 317（指令授权账本 IAL）** 指令事件 e = (speaker, auth_proof, scope, delegation_chain, t, provenance_hash, nonce, revocation)。contract_valid(e) ⇔ authenticated ∧ scope ⊇ goal(e) ∧ ¬expired ∧ ¬replayed ∧ ¬revoked ∧ consistent(K)。只有 contract_valid 指令可收窄 𝒩；否则降级为 suggestion。

**定义 318（授权代数 ADA）** 委托 D: a → a′ 要求 a′ ⪯ a（单调不增），链式复合 scope 只缩不扩；根授权来自宪法 K，任何委托都不能扩张根。越权（a′ ⋠ a）与「糊涂代理」（把第三方请求当成自身授权）一律拒绝并记账。

**定义 319（来源防火墙 PCR）** 指令/数据分离：只有通过身份与来源门控的文本进入规范层；观测中的第三方文本、网页字样、环境标注一律隔离为 *observation*（可作证据，不可作授权）。门控 fail-closed，误放率有上界（A99）。

**定义 320（指令冲突裁决 CCR）** 冲突优先级 = 权威层级 > 时效 > 具体性。但若向高优先级裁决会把某动作判为不安全、而向低优先级判为安全，则该冲突为**安全关键冲突**，不得自动裁决，必须升级澄清/拒绝。

**定义 321（威胁模型 ℰ_inst）** 注入（观测文本冒充指令）、重放/陈旧指令、胁迫指令、越权指令、木马组合（单条无害、组合有害）、语义规避（委婉语绕过安全过滤）。并入 AIC：ℰ_LIRA = ℰ_FLUID × ℰ_inst。

**定义 322（规范契约监视器 NCM）** 运行时核验已执行轨迹：是否达成 g、满足 C、risk ≤ ρ？区分**违约**（明确违反）与**契约漂移**（逐步偏离意图）；漂移复用 R69 FMA 的行为似然通道（Δa↑ 而 r_res 正常 ⇒ 非传感器问题，而是契约偏离）。

**定义 323（意图校准门 ICG）** 意图后验需校准：ECE_int 对齐事后人工反馈。ECE_int > τ ⇒ 禁用自主消歧，强制澄清或拒绝（R69 MCG 的规范层镜像）。

**定义 324（安全拒绝与最小伤害回退 SRL）** 不可行/未授权时执行最小伤害回退（停/保持/回安全位），且拒绝本身不得制造新危险（例如停在危险处）；同时发出**结构化澄清请求**（给出可行集与权衡），而非空泛的「我不懂」。

**定义 325（协商契约 NCO）** 人机协商：系统提交执行集 ℰ 与权衡；人的选择成为带授权的新指令；协商次数受 R69 交互预算约束。对齐从一次性映射变成可审计的对话。

**定义 326（宪法版本与证书 J_LIRA）** 宪法 K 版本化，变更需更高授权并留痕（防「宪法漂移」/元层 Goodhart）。J_LIRA = (J_FLUID, contract_valid, authority_chain_hash, intent_ece, χ_max, over_refusal, under_refusal, conflict_events, provenance_coverage, constitution_ver)。Valid ⇔ Valid(J_FLUID) ∧ contract_valid ∧ ECE_int ≤ τ ∧ 无未决安全关键冲突 ∧ provenance_coverage ≥ τ_p。

## 2. 关键算法骨架

```python
# IP-264 IIS：指令 → 意图后验 + 澄清集（冻结语言模型接地，事件驱动）
def interpret_instruction(x, h_t, ledger, pcr):
    trusted = pcr.is_instruction_channel(x)          # 来源门控（IP-269）
    verdict = ledger.verify(x) if trusted else Verdict.invalid("untrusted")
    post    = frozen_llm.ground(x, h_t).calibrate()  # p(I|x,h_t) + ICG（IP-272）
    if not verdict.valid:                            # 未授权 → 只能当建议
        return IntentPosterior(post, mode="suggestion", scope=None)
    return IntentPosterior(post, mode="contract", scope=verdict.scope)

# IP-265 SCA：三分判定（执行集 = 规范集 ∩ 物理安全 ∩ 能力）
def resolve(post, K, S_phys, capability):
    items = []
    for I, w in post.weighted():
        N = normative_set(I) & K                     # 宪法并入，恒 N ⊆ K
        E = N & S_phys & capability
        items.append(Item(I, w, E, risk_range(E, I.rho)))
    if all(it.E.empty for it in items):
        return Decision("INFEASIBLE", items)
    if safety_class_disagrees(items):                # 不同意图翻转安全分类
        return Decision("UNDERDETERMINED", items, chi=safety_conflict_mass(items))
    return Decision("EXECUTABLE", items)

# IP-266 SWCG：安全关键歧义优先的澄清；无预算 → 保守补全并标记过拒
def choose_clarification(dec, budget, kappa):
    best = None
    for g in clarify_candidates(dec.items):
        if not budget.allow(g): continue
        s = expected_entropy_drop(dec.items, g) * (1 + kappa * dec.chi(g)) - cost(g)
        if best is None or s > best.s: best = (g, s)
    if best and best.s > 0:
        return ("CLARIFY", best.g)
    I_safe = min(dec.items, key=lambda it: it.risk_range.max).I
    return ("CONSERVATIVE", I_safe, flag_over_refusal=True)

# IP-267/268 IAL + ADA：授权账本与单调委托
class InstructionLedger:
    def verify(self, e):
        ok = (authenticate(e) and not e.expired and not self.seen(e.nonce)
              and not self.revoked(e.id) and e.scope.covers(e.goal)
              and consistent_with_constitution(e))
        return Verdict(ok, scope=e.scope, chain_hash=self.chain_hash(e))
    def delegate(self, parent_scope, child_scope):
        assert child_scope <= parent_scope            # 越权即拒绝并记账
        return parent_scope.intersect(child_scope)

# IP-270 CCR：冲突裁决（安全关键冲突不自动裁决）
def resolve_conflict(x1, x2):
    order = priority(x1, x2)                          # 权威 > 时效 > 具体性
    if safety_class_flips(x1, x2, order):
        return ("ESCALATE", "safety-critical conflict")
    return ("RESOLVE", order.winner)

# IP-273/274 SRL + NCO：安全拒绝、结构化请求与协商
def refuse_or_negotiate(dec, K, M):
    fallback = least_harm_fallback(K, M.S_phys)       # 停/保持/回安全位，不制造新险
    options  = feasible_frontier(dec.items)           # 给人类可选项与权衡
    M.srl.emit_structured_request(options)            # 「可选 A/B，需授权」
    return fallback

# IP-277 主闭环（继承 FLUID/R68，在「意图」处插入规范闸门）
def LIRA_RAS_round(M, obs):
    z, o = M.mtm.forward(...); c, U_cal, _ = M.cof.step(...)
    post = M.iis.interpret_instruction(obs.instruction, M.history, M.ledger, M.pcr)
    if post.mode == "suggestion":                     # 未授权不进入规范层
        post = post.as_prior_only()
    dec = M.sca.resolve(post, M.K, M.S_phys, M.cap)
    if dec.kind == "INFEASIBLE":
        return M.srl.refuse_or_negotiate(dec, M.K, M)
    if dec.kind == "UNDERDETERMINED":
        act, arg = M.swcg.choose_clarification(dec, M.budget, M.kappa)
        if act == "CLARIFY":
            ans  = M.cia.execute(arg)                 # 复用 R69 问/看/触 + 证据纪律
            post = M.cia.update_intent(post, ans)
            dec  = M.sca.resolve(post, M.K, M.S_phys, M.cap)
        else:                                         # CONSERVATIVE
            post = post.narrow_to(arg); dec = M.sca.resolve(post, M.K, M.S_phys, M.cap)
    # 在 E = N ∩ S_phys ∩ Cap 内执行：复用 FLUID 流策略与两级退避
    k, lam, mode, unc = M.fluid_round(obs, feasible=dec.set, contract=post)
    M.ncm.verify(M.last_traj, post)                   # IP-271 运行时契约监视
    M.vqa_l.submit_async(post, dec, k, lam)           # 参与式审计（继承 R69）
    return k, lam, mode, unc, M.jlira.certify(post, dec)
```

## 3. 推导

**引理 19（安全关键歧义的澄清价值支配）** 在双边损失（定义 315）下，把单位澄清预算投给 χ 最高的歧义，其对齐损失下降 ≥ 投给 χ=0 的良性歧义的 (1 + κ·χ_min) 倍（A101：澄清动作对意图身份非退化）。系：R69 的 VoI 排序在 χ 不均匀时次优——**先问「会不会撞人」，再问「左一点还是右一点」**。

**引理 20（过度拒绝不是免费的）** 设保守补全把意图后验塌缩到风险最小意图 I_safe，则 under_service ≥ P(I ≠ I_safe)·G，其中 G 为该意图下的可达收益差。故存在由 (α, β, ρ) 决定的内部最优；β → ∞ 时 over_refusal → 1，L_align 可能高于适度执行。**永远拒绝的机器人是安全的，但对齐度为 0。**

**引理 21（来源防火墙的注入上界）** 若来源分类器误放率 ≤ δ、nonce 重放保护覆盖率 ≥ 1−ε_r，则注入指令进入规范层的概率 ≤ δ + ε_r + ε_parse（解析歧义，A99）。系：**指令安全的上界由来源完整性决定，而非策略能力决定**。

**定理 18（非扩张不变式 / 语言不能洗白安全）** 在不变式 (i)(ii) 与定义 317–319 下，对任意（含对抗）指令序列，执行动作集 ⊆ 𝒮_phys ∩ K。语言只能收窄 𝒩，永不扩张物理安全包络。推论：**「用户让我做的」永远不是安全豁免**；R69 的「问错」风险被推广并封堵——问错最多导致更保守，不会导致越界。

**定理 19（三分完备性与无静默松弛）** 每条指令必落入可执行/不可行/欠定之一；系统不通过放松 K 把不可行变可执行；安全关键冲突不自动裁决（定义 320）。故规范层不存在「静默降级」。

**定理 20（能力不能替代授权 / 分离定理）** 对齐损失中由未授权执行贡献的部分下界为 P(¬contract_valid ∧ executed)，该量只依赖授权链与来源门控，与策略能力 Cap_θ、世界模型精度无关。即**更强的策略不能修复一个坏的授权根**：能力提升只能降低 ℰ 内的执行误差，不能改变门控。

**定理 21（LIRA 对 FLUID/R68 的安全侧严格包含）** 当所有指令 contract_valid 且 𝒞(x) 单点（无歧义）时，LIRA 逐指令退化为 FLUID → R68；当存在不可行/未授权/安全关键歧义时，执行集严格更小且安全侧不变差。故链条为 **R68 ⊂ R69 ⊂ R70**：R68 在不确定性上只收紧，R69 在可消解时可松开，R70 用规范闸门保证松开也永不越过安全边界。

## 6. 本轮最大风险

**一句话**：LIRA-RAS 的全部安全保证都是「相对于某个授权根与宪法 K」而言的——**如果根本身是坏的（宪法过时/被俘获/写入了错误规范），或来源门控被训练数据偏差长期骗过，系统就会「完美地对齐到一个错误的权威」：它严格守住了一条错的边界，把「越权」与「合规」都按一份坏合同盖章**——**对齐到字面正确的坏宪法，比明显地不听话更危险，因为它看起来毫无破绽**。

**次级风险与缓解**：
1. **来源门控本身是可学习攻击面** → 定义 319 结构化隔离 + 引理 21 上界 + 红队持续注入训练；
2. **含义漂移/语义规避** → 冻结 LLM + 结构化澄清集 + E315 长程指令风格漂移监测；
3. **过拒被当成安全** → 双边损失（定义 315）+ 引理 20 + E304/E310 显式度量；
4. **协商协议被社交工程利用** → 协商只提可行集与权衡、不暴露内部阈值；选择仍需授权记账（定理 20）；
5. **实时性** → 语言接地事件驱动、与控制环解耦，控制环增量 < 0.5ms。

## 2. 形式化定义（要点版）

**定义 310（总览与四不变式）** (i) 非扩张：𝒩_{t+1} ⊆ 𝒩_t ⊆ K，语言永不扩张 𝒮_phys；(ii) 授权完整性：未验证指令仅作建议；(iii) 澄清先于承诺：安全关键歧义不得静默向高风险消歧；(iv) 继承 R69 证据纪律与交互预算。

**定义 311–312（意图、指令观测与执行集）** 指令是意图的有损观测；`𝒞(x)=supp p(I \mid x,h)`；`𝒩(I)` 为满足目标/约束/偏好的轨迹集并入宪法 K；`ℰ(I)=𝒩(I)∩𝒮_phys∩Cap_θ`，恒 `𝒩(I)⊆K` 且 `𝒮_phys∩K` 与语言无关。

**定义 313–314（三分与不确定性）** 可执行 / 不可行 / 欠定；`U_int_ale`（意图内噪声）与 `U_int_epi = I(I; 安全动作类)`；风险耦合 `χ = P_I(ℰ(I) 含违反 ρ 的动作)`——只有 χ 高的歧义才优先澄清。

**定义 315（双边对齐损失）** `L_align = α·E[不安全执行] + β·E[拒绝安全意图] + γ·E[静默曲解]`；纯保守使 β 项爆炸，不是对齐；最优点一般不在「最大安全」端点。

**定义 316（SWCG）** `g* = argmax [E[ΔH]·(1+κχ) − c]`；≤0 或无预算 → 保守补全（取最小最大风险意图）并标记过拒。

**定义 317–318（IAL 与 ADA）** `contract_valid ⇔ 认证∧域⊇目标∧未过期∧未重放∧未撤销∧合宪`；委托 `a′⪯a`，scope 只缩不扩；越权与糊涂代理一律拒绝记账。

**定义 319（PCR）** 指令/数据分离：只有可信指令通道进制规范层；第三方文本/网页/环境标注隔离为 observation；fail-closed。

**定义 320（CCR）** 优先级 = 权威 > 时效 > 具体性；若裁决翻转安全分类 ⇒ 安全关键冲突，不得自动裁决，升级澄清/拒绝。

**定义 321（ℰ_inst）** 注入 / 重放 / 胁迫 / 越权 / 木马组合 / 语义规避；`ℰ_LIRA = ℰ_FLUID × ℰ_inst`。

**定义 322–323（NCM 与 ICG）** 运行时核验违约 vs 契约漂移（复用 FMA：Δa↑ 且 r_res 正常 ⇒ 契约偏离）；`ECE_int>τ` ⇒ 禁用自主消歧 → 强制澄清/拒绝。

**定义 324–326（SRL/NCO/证书）** 最小伤害回退且拒绝不制造新险 + 结构化请求；协商只提可行集与权衡，选择需授权记账；宪法版本化防漂移；J_LIRA 并入契约、授权链、ECE、χ、双边拒绝率、冲突、来源覆盖。

## 3. 关键算法伪代码

```python
# IP-264 IIS：指令 → 意图后验 + 澄清集（冻结 LLM，事件驱动）
def interpret_instruction(x, h_t, ledger, pcr):
    trusted = pcr.is_instruction_channel(x)          # 来源门控 IP-269
    verdict = ledger.verify(x) if trusted else Verdict.invalid("untrusted")
    post    = frozen_llm.ground(x, h_t).calibrate()  # 意图校准 IP-272
    return IntentPosterior(post, "contract" if verdict.valid else "suggestion",
                           scope=verdict.scope)

# IP-265 SCA：三分判定
def resolve(post, K, S_phys, capability):
    items = [Item(I, w, (normative_set(I) & K) & S_phys & capability, risk_range(...))
             for I, w in post.weighted()]
    if all(it.E.empty for it in items):        return Decision("INFEASIBLE", items)
    if safety_class_disagrees(items):          return Decision("UNDERDETERMINED", items,
                                                              chi=safety_conflict_mass(items))
    return Decision("EXECUTABLE", items)

# IP-266 SWCG：安全关键歧义优先；无预算 → 保守补全 + 过拒标记
def choose_clarification(dec, budget, kappa):
    best = max(((g, expected_entropy_drop(dec.items, g) * (1 + kappa*dec.chi(g)) - cost(g))
                for g in clarify_candidates(dec.items) if budget.allow(g)),
               key=lambda t: t[1], default=None)
    if best and best[1] > 0: return ("CLARIFY", best[0])
    return ("CONSERVATIVE", min(dec.items, key=lambda it: it.risk_range.max).I, True)

# IP-267/268 IAL + ADA：授权账本与单调委托
class InstructionLedger:
    def verify(self, e):
        return Verdict(authenticate(e) and not e.expired and not self.seen(e.nonce)
                       and not self.revoked(e.id) and e.scope.covers(e.goal)
                       and consistent_with_constitution(e),
                       e.scope, self.chain_hash(e))
    def delegate(self, parent, child):
        assert child <= parent                  # 越权即拒绝并记账
        return parent.intersect(child)

# IP-270 CCR：安全关键冲突不自动裁决
def resolve_conflict(x1, x2):
    order = priority(x1, x2)                     # 权威 > 时效 > 具体性
    return ("ESCALATE", "safety-critical") if safety_class_flips(x1, x2, order) \
           else ("RESOLVE", order.winner)

# IP-277 主闭环（继承 FLUID/R68）
def LIRA_RAS_round(M, obs):
    z, o = M.mtm.forward(...); M.cof.step(...)
    post = M.iis.interpret_instruction(obs.instruction, M.history, M.ledger, M.pcr)
    if post.mode == "suggestion": post = post.as_prior_only()
    dec = M.sca.resolve(post, M.K, M.S_phys, M.cap)
    if dec.kind == "INFEASIBLE": return M.srl.refuse_or_negotiate(dec, M.K, M)
    if dec.kind == "UNDERDETERMINED":
        act, arg, *_ = M.swcg.choose_clarification(dec, M.budget, M.kappa)
        if act == "CLARIFY":
            post = M.cia.update_intent(post, M.cia.execute(arg))   # 复用 R69
        else:
            post = post.narrow_to(arg)
        dec = M.sca.resolve(post, M.K, M.S_phys, M.cap)
    k, lam, mode, unc = M.fluid_round(obs, feasible=dec.set, contract=post)
    M.ncm.verify(M.last_traj, post); M.vqa_l.submit_async(post, dec, k, lam)
    return k, lam, mode, unc, M.jlira.certify(post, dec)
```

## 4. 推导

**引理 19（安全关键歧义的澄清价值支配）** 双边损失下，把单位预算给 χ 最高的歧义，其损失下降 ≥ 给 χ=0 良性歧义的 `(1+κχ_min)` 倍（A101）。系：R69 的 VoI 排序在 χ 不均匀时次优——先问「会不会撞人」，再问「左一点还是右一点」。

**引理 20（过度拒绝不是免费的）** 保守补全塌缩到最小风险意图 I_safe，则 `under_service ≥ P(I≠I_safe)·G`；β→∞ 时 `over_refusal→1`，L_align 可能高于适度执行。永远拒绝的机器人安全但对齐度为 0。

**引理 21（来源防火墙的注入上界）** 误放率 δ + 重放漏检 ε_r + 解析歧义 ε_parse 是注入进入规范层的上界（A99）。指令安全的上界由来源完整性决定，而非策略能力。

**定理 18（非扩张 / 语言不能洗白安全）** 在四不变式与 IAL/PCR/ADA 下，任意（含对抗）指令序列的执行动作集 ⊆ `𝒮_phys ∩ K`；语言只能收窄 𝒩。推论：「用户让我做的」永远不是安全豁免；R69 的「问错」最多导致更保守，不会导致越界。

**定理 19（三分完备性与无静默松弛）** 每条指令必属三分之一；不通过放松 K 把不可行变可执行；安全关键冲突不自动裁决 ⇒ 规范层不存在静默降级。

**定理 20（能力不能替代授权 / 分离定理）** 未授权执行贡献的对齐损失下界为 `P(¬contract_valid ∧ executed)`，只依赖授权链与来源门控，与 Cap_θ、世界模型精度无关。更强的策略不能修复坏的授权根。

**定理 21（严格包含）** 全 contract_valid 且 `𝒞(x)` 单点时，LIRA 逐指令退化为 FLUID → R68；存在不可行/未授权/安全关键歧义时执行集严格更小且安全侧不变差。链条：**R68 ⊂ R69 ⊂ R70**。

## 7. 本轮最大风险

**一句话**：LIRA-RAS 的全部安全保证都是「相对于某个授权根与宪法 K」而言的——**若根本身是坏的（宪法过时/被俘获/写入错误规范），或来源门控被训练偏差长期骗过，系统就会完美地对齐到一个错误的权威：它严格守住一条错的边界，把越权与合规都按一份坏合同盖章**——**对齐到字面正确却实质错误的宪法，比明显地不听话更危险，因为它看起来毫无破绽**。

**次级风险与缓解**：来源门控本身是可学习攻击面（结构化隔离 + 引理 21 + 红队注入训练）；语义漂移/委婉规避（冻结 LLM + 澄清集 + E315）；过拒被当成安全（双边损失 + 引理 20 + E304/E310）；协商被社交工程（只提可行集与权衡、选择需授权记账，定理 20）；实时性（语言接地事件驱动、与控制环解耦，增量 < 0.5ms）。
