## 1. 本轮直觉

**灵感 4（嵌入式系统 → 这是一场硬实时资源分配考试）**
直觉：180s 硬上限、每步延迟与抖动被记录、N 端口共享算力、真人干预是异步外部事件——这四件事合起来，正是嵌入式实时系统的经典约束：硬截止时间（hard deadline）、有限算力、确定性（determinism）、异步中断与优雅降级（graceful degradation）。因此真正的决策变量不是「模型多大」，而是**在有限 episode 预算内，把算力、开环 chunk、重试、干预响应四种资源分配到哪些时刻**。反直觉点：**更大的模型/更多的 test-time compute 不必然提分；在硬截止下，计算的价值取决于它落在时间轴的哪个位置。**

**灵感 5（论文创新点 → 从「工程集成」升级为「可证伪论点」）**
直觉：审稿人不会为「我们用了 SAM、LoRA、group DRO、CUDA Graph」买单；会为一个**清晰的问题形式化 + 非平凡机制 + 可证伪预测 + 统计上站得住的证据**买单。本轮因此做一次自我审计：把 I1–I8 重写成三条 claim，每条都必须回答「去掉它论文还剩什么」「它与已有工作的边界在哪」「什么实验结果会证伪它」。

**两者统一**：中心论点从「做一个更强的通才策略」改为——**「评测分布偏移下的通才操作，本质是硬截止预算下的数据—诊断—计算联合分配问题」**。I1 管数据分配，I2 管诊断/训练预算分配，I9 管推理时间分配，三者共享同一个「把有限资源投向计分轴最痛处」的原则。

## 2. 中心论点（本轮新立）

> **T1**：在 5 轴评测分布偏移 + 180s 硬截止 + 单模型约束下，提升平均成功率与步骤分的主导杠杆不是模型容量，而是三类资源的**对齐分配**：
> (a) 训练数据向评测轴对齐（I1）；
> (b) 诊断/训练预算向高失败族对齐，且用分层收缩抵抗小样本噪声（I2）；
> (c) 推理算力与开环长度向「剩余时间 slack × 接触风险」对齐（I9）。
> 可证伪预测：若把三类分配全部关掉、只保留官方基线 + 均匀训练，则平均分显著下降；且任一类分配单独开启的增益，应能在族级（而非单任务级）被统计显著地测到。

## 3. 严谨定义（本轮核心）

### 3.1 预算约束目标
设 episode 预算 \(B=180\text{s}\)，第 \(k\) 步选 chunk 长度 \(a_k\)、计算模式 \(m_k\in\{\text{fast},\text{full},\text{foresight}\}\)，单步成本 \(c(m_k,a_k)\)，进度增量 \(\Delta s_k\ge 0\)（对齐里程碑步骤分），成功率指示 \(S\in\{0,1\}\)。策略优化：
\[
\max_{\pi}\ \mathbb{E}\Big[\mathbb{1}[S]+\eta\sum_k \Delta s_k\Big]
\quad\text{s.t.}\quad
\sum_k c(m_k,a_k)\le B,\ \ \mathrm{p99}(\text{latency})\le L_{\max},\ \ \pi\in\text{单模型}.
\]
\(L_{\max}\) 官方未公开（F11），暂以「真机空跑标定的控制周期 \(1/3\)」为内部目标，标定前不写死。

### 3.2 I1 的不变性/等变性二分
设观测 \(o=(I,s,l)\)、专家动作 \(a\)、评测轴干预算子 \(T_g\)。评测分布可视为训练分布在五轴上的干预混合。关键是**两类轴在数学上不同**：
- **干扰轴** \(g\in\{\text{background},\text{distractor},\text{appearance}\}\)：只改任务无关因子，要求**不变性** \(\pi_\theta(T_g o)=\pi_\theta(o)\)。
- **几何轴** \(g=\text{pos}\)：\(T_{\text{pos}}\in SE(3)\) 改变目标/初始位姿，要求**等变性** \(\pi_\theta(T_{\text{pos}}o)=T_{\text{pos}}\odot\pi_\theta(o)\)。该式只在 **ee 控制空间**成立；joint 空间需经 IK 重定向，不是简单线性等变——这是位置增广必须单独处理、且可能影响 `control_space` 选择的原因。
- **人为干扰轴**：不是离线数据变换，而是在线事件，交给 I4，不纳入 I1 的增广混合。

### 3.3 I2 的小样本现实
每任务 10 次、每轴仅 2 次。对 \(p=0.5,n=10\)，95% 置信区间约 \(\pm 31\)pp；每轴 \(n=2\) 基本不可估计。故 I2 的估计单元必须是**任务族**而非单任务，且必须用分层收缩；否则「1/成功率」加权是在把估计噪声当信号放大。

### 3.4 论文创新边界（明确不宣称什么）
- 不宣称图像增广、LoRA、group DRO、anytime algorithm 本身是新的；
- 宣称的新意是：**评测轴对齐 + 动作语义证书 + 支撑约束**的增广框架（C1）；**面向每轴 n=2 的族级分层诊断与平均锚定 CVaR**（C2）；**里程碑感知的硬截止 anytime 调度**（C3）。

## 5. 研究问题（本轮收敛为 Q1–Q6）

- **Q1（增广的语义保真）**：如何用「不变性 + 等变性 + 支撑约束 + 有效性证书」保证增广不引入动作语义漂移？证书模型自身如何避免循环验证？
- **Q2（小样本诊断）**：在每轴 n=2、每任务 n=10 的评测下，如何用族级分层收缩把失败率变成稳定的训练权重，而不伤强任务？
- **Q3（诊断预算）**：免费的沙盒 trial 应如何在 32 任务/若干族之间分配，才能最大化族级失败率估计的信息增益？
- **Q4（干预感知）**：手部检测 + 历史栈能否在 <100ms 判别「世界被外力改写」，并让位-重估-续做不与 180s 冲突？
- **Q5（硬截止调度）**：给定剩余时间 slack 与接触风险，如何联合选 chunk 长度、计算模式与「朝最近里程碑」的降级策略，使步骤分最大且 p99 不恶化？
- **Q6（单模型边界）**：调度器内的 fast/full 切换若只改采样步数/分辨率而不换权重，是否合规？伺服/世界模型等模块的边界需书面求证。

## 6. 设计原则（PR1–PR6）

- **PR1 计分轴对齐律**：每个决策必须指明作用于哪条轴（5 泛化 × 步骤分 × 180s）；指不出就不做。
- **PR2 单模型边界律**：一个参赛实体 = 一个策略服务；模块化可，按任务切换不同模型/权重不可；fast 模式只能改同一权重的采样步数/分辨率。
- **PR3 干预安全律**：检测到人手在执行域内 → 降速/停持并重估；「继续」以「手已离开 + 重估完成」为前提。
- **PR4 部署预算律**：p99 延迟与动作健康度是发布门禁；先过 run_client + 延迟基准，再上真机。
- **PR5 硬截止律（新）**：任何优化都必须报告它对 180s 预算与 p99 抖动的影响；只提成功率、不提时间账的改进不算通过。
- **PR6 可证伪律（新）**：每个创新点必须写出「什么结果会证伪它」与「在现有 n=10/轴=2 下需要什么聚合层级才能检验」；写不出就不进论文主线。

## 1. I1 深化：轴对齐、动作语义保持的增广引擎

### 1.1 直觉 → 定义
直觉：背景/杂物/外观变了，动作语义不该变；目标位置变了，动作应跟着做刚体变换。前者是**不变性**，后者是**等变性**——把两者混为一谈，是位置增广最容易出物理不可行动作的原因。

定义：设观测 \(o=(I,s,l)\)、专家动作 \(a\)、评测轴干预算子 \(T_g\)。
- 干扰轴 \(g\in\{\text{background},\text{distractor},\text{appearance}\}\)：要求
  \[
  \pi_\theta(T_g o)=\pi_\theta(o).
  \]
- 几何轴 \(g=\text{pos}\)：\(T_{\text{pos}}\in SE(3)\)，要求
  \[
  \pi_\theta(T_{\text{pos}}o)=T_{\text{pos}}\odot\pi_\theta(o).
  \]
  该式在 **ee 控制空间**精确；joint 空间需 IK 重定向，只能近似。因此位置增广优先在 ee 空间做，或把变换限制在目标/放置点而非整条 joint 轨迹。
- 人为干扰轴不进入离线增广，交给 I4/I9 在线处理。

训练目标：
\[
\mathcal{L}=\mathcal{L}_{\text{task}}
+\lambda_n\,\mathbb{E}_{g\in G_{\text{nuis}}}\,d\big(\pi(T_g o),\pi(o)\big)
+\lambda_e\,\mathbb{E}_{T_{\text{pos}}}\,d\big(\pi(T_{\text{pos}}o),T_{\text{pos}}\odot\pi(o)\big)
+\lambda_s\,\mathcal{R}_{\text{support}}.
\]

### 1.2 有效性证书（本轮对第 1 轮最大风险的直接回应）
一条增广样本 \((o,a)\to(o',a')\) 只有同时通过四关才入池：

1. **视觉真实度**：判别器/重建误差 \(D_\psi(o')>\tau_v\)，排除 inpainting 边缘、光照不一致。
2. **物理可行**：无碰撞、关节限位内、目标可达、抓取段物体-夹爪相对位姿保持。
3. **动作语义一致**：用**跨任务留出**训练的逆动力学/动作语义模型 \(f_\phi\) 检验
   - 干扰轴：\(f_\phi(o',a)\approx f_\phi(o,a)\)；
   - 位置轴：\(f_\phi(o',T_{\text{pos}}\odot a)\approx f_\phi(o,a)\)。
4. **支撑约束**：变换参数 \(\xi\) 满足 \(\|\xi\|_{\Sigma}\le\kappa\)，\(\Sigma\) 由训练集目标/物体位姿分布估计，避免把样本推到训练支撑之外。

> 去循环验证：\(f_\phi\) 必须用与增广任务不相交的任务族训练，并保留人工抽检与对抗伪影集；否则证书只是在验证自己的偏差。

### 1.3 伪代码
```python
class CertifiedAugmentor:
    def augment_episode(self, ep):
        out = []
        for axis in sample_axes(p={"background": .4, "distractor": .4,
                                   "appearance": .2, "position": .2}):
            ep2, xi = apply_axis(ep, axis)          # 位置轴返回 SE(3) 参数 xi
            if not self.certificate(ep, ep2, axis, xi):
                continue
            out.append(ep2)
        return out

    def certificate(self, ep, ep2, axis, xi):
        if D_psi(ep2.images) < TAU_V:                       return False
        if not (collision_free(ep2) and within_limits(ep2)
                and reachable(ep2) and grasp_pose_preserved(ep, ep2)):
            return False
        if not semantic_consistent(f_phi, ep, ep2, axis, xi): return False
        if mahalanobis(xi, SIGMA_SUPPORT) > KAPPA:          return False
        return True

    def semantic_consistent(self, f, ep, ep2, axis, xi):
        if axis in {"background", "distractor", "appearance"}:
            return dist(f(ep2.o, ep2.a), f(ep.o, ep.a)) < EPS_SEM
        if axis == "position":
            return dist(f(ep2.o, transform_ee(ep2.a, xi)),
                        f(ep.o, ep.a)) < EPS_SEM
```

### 1.4 位置轴：技能段重组
- 把轨迹切成 `approach / grasp / transport / place` 四段；`grasp` 段锚定物体，不做整段刚体变换；
- 只在 `transport` 与 `place` 边界施加 \(T_{\text{pos}}\)，并对夹爪-物体相对位姿做保持约束；
- 变换幅度受 \(\kappa\) 限制，超限样本丢弃而非裁剪（裁剪会制造不连续）。

### 1.5 验收与消融
- 离线：证书通过率、伪影率、动作语义漂移（\(d\) 的分布）、物理不可行率。
- 真机沙盒：每轴单独开 vs 全开 vs 不开；每族至少 2 任务、每任务 ≥30 次，报告族级 CI。
- 保留判据：任一新轴在族级相对增益 ≥ 离线预测的 50%，且强任务不回退。

## 2. I2 深化：族级分层诊断与平均锚定 CVaR

### 2.1 为什么必须族级：功效计算
评测每任务 10 次、每轴仅 2 次。对 \(p=0.5\)：

| n | 95% CI 半宽 | 备注 |
|---|---|---|
| 2（单轴） | ±69pp | 几乎不可估计 |
| 10（单任务） | ±31pp | 单任务排名不可信 |
| 60（约 6 任务族） | ±12.6pp | 族级可用 |
| 320（全榜） | ±5.5pp | 独立假设；聚类后更宽 |

在 \(p\approx0.35\)、双侧 \(\alpha=0.05\)、power=0.8 下，两臂对照约需：10 次/臂只能检出 ~60pp 巨效应；90 次/臂可检出 ~20pp；353 次/臂才可检出 ~10pp。**结论：任何单任务/单轴的真机结论都不可靠；I2 的估计单元必须是族，且论文只能做族级/整体 claim。**

### 2.2 分层模型
对任务 \(t\)、族 \(f=f(t)\)，沙盒成功计数 \(y_t\sim\text{Binomial}(n_t,p_t)\)：
\[
\operatorname{logit}p_t=\mu_{f(t)}+u_t,\quad
u_t\sim\mathcal{N}(0,\sigma_f^2),\quad
\mu_f\sim\mathcal{N}(\mu_0,\tau^2).
\]
用经验贝叶斯/部分池化得到后验 \(\hat p_t\) 与族失败风险
\[
R_f=1-\frac{1}{|f|}\sum_{t\in f}\hat p_t,
\]
并取后验下分位数 \(R_f^{\text{LCB}}\) 作为保守估计。

### 2.3 训练目标：平均锚定 CVaR
比赛主序是**平均**成功率，不是 worst-case；纯 group DRO 可能伤平均。用：
\[
\mathcal{L}(\theta)=\mathbb{E}_{t}[\ell_t(\theta)]
+\lambda\cdot\mathrm{CVaR}_{\alpha}\big(\{R_f(\theta)\}\big),
\quad \lambda\in\{0,0.1,0.3,1.0\}.
\]
实现上用后验样本近似 CVaR，等价于对高失败族做指数梯度加权；采样权重
\[
w_t\propto\exp\big(\beta\,R_{f(t)}^{\text{LCB}}\big),\quad
w_t\in[w_{\min},w_{\max}],
\]
强任务保留下限 \(w_{\min}\)，防止被弱族挤掉。梯度冲突用 per-family 梯度余弦监控，冲突为负时启用 PCGrad。

### 2.4 诊断预算分配
沙盒免费但时段有限。不要 32 任务均分，而是贪心最大化族级后验方差下降：
\[
t^\*=\arg\max_{t}\ \mathrm{Var}(R_{f(t)}\mid y)\cdot v_{f(t)},
\]
\(v_f\) 为该族在计分中的权重（任务数 × 是否高险）。每轮跑 1 个 trial，更新后验，重复至预算耗尽。这样在相同沙盒次数下把族级 CI 压得更窄。

### 2.5 伪代码
```python
def diagnose_and_weight(tasks, families, budget):
    counts = {t: [0, 0] for t in tasks}          # [success, n]
    for _ in range(budget):
        f = max(families, key=lambda f: post_var(f) * value[f])
        t = max(tasks_in(f), key=lambda t: post_var(t))
        counts[t][0] += run_sandbox_trial(t)
        counts[t][1] += 1
        update_posterior(counts)                 # partial pooling
    R = {f: 1 - mean(post_p[t] for t in tasks_in(f)) for f in families}
    R_lcb = {f: lower_quantile(R[f], 0.05) for f in families}
    w = normalize({t: exp(beta * R_lcb[family[t]]) for t in tasks})
    w = clip(w, W_MIN, W_MAX)
    return w, R

def train_step(batch):
    loss = sum(w[t] * task_loss(batch[t]) for t in batch) / sum(w.values())
    loss += lam * cvar_alpha([risk[f] for f in families], alpha=0.25)
    return loss
```

### 2.6 与第 1 轮 I2 的差异
第 1 轮是「1/族成功率软加权 + PCGrad」；本轮改为**部分池化估计 + 后验 LCB + 平均锚定 CVaR + 诊断预算分配**。核心升级是把「估计噪声」显式建模，而不是把 10 次观测当真实成功率。

## 3. I9 新增：截止时间感知的 anytime 调度器

### 3.1 形式化
episode 预算 \(B=180\text{s}\)，第 \(k\) 步选 chunk 长度 \(a_k\) 与模式 \(m_k\)，单步成本 \(c(m_k,a_k)\)，进度 \(\Delta s_k\)（里程碑步骤分）。目标：
\[
\max\ \mathbb{E}\Big[\mathbb{1}[S]+\eta\sum_k\Delta s_k\Big]
\ \text{s.t.}\ \sum_k c(m_k,a_k)\le B,\ \ \mathrm{p99}\le L_{\max},\ \ \text{单模型}.
\]
定义归一化 slack
\[
s_k=\frac{B-t_k-\hat T_{\text{rem}}(k)}{B},
\]
其中 \(\hat T_{\text{rem}}\) 来自进度头/任务先验；接触风险 \(r_k\in[0,1]\) 来自关键点距离/阶段分类器。

### 3.2 调度策略（slack × 风险 × 里程碑）
| slack \(s_k\) | 条件 | 模式 | chunk |
|---|---|---|---|
| >0.5 | \(r_k>0.6\)（近接触） | full（多步去噪） | 1–2 |
| >0.5 | 否则 | full | 4 |
| 0.2–0.5 | \(r_k<0.3\) | full | 8 |
| 0.2–0.5 | 否则 | full | 4 |
| 0.05–0.2 | 任意 | fast（同权重少步/低分辨率） | 8 |
| ≤0.05 | 任意 | milestone fallback（朝最近得分点） | 4 |

- **fast 模式只改同一权重的采样步数/输入分辨率，不换模型/权重**（PR2）。
- **降级顺序**：foresight → full → fast → milestone fallback → safe_hold；每一级都记录延迟，供 PR4 门禁。
- **干预覆盖**：检测到手 → 立即 YIELD（safe_hold），与 slack 无关；设 TTL 上限，手离开且重估完成后恢复，恢复时 chunk=4。
- **里程碑优先**：当 \(s_k\le0.05\)，不再赌完整任务，而是朝最近的 100 分制里程碑动作，保住步骤分（F10）。

### 3.3 伪代码
```python
class DeadlineScheduler:
    def decide(self, t, obs, prog):
        s = (B - t - prog.est_remaining(obs)) / B
        r = prog.contact_risk(obs)
        if self.hand.detect(obs.images[-1]) or self.interrupted(obs):
            return Mode("yield", chunk=1)
        if s > 0.5:
            return Mode("full", chunk=1 if r > 0.6 else 4)
        if s > 0.2:
            return Mode("full", chunk=8 if r < 0.3 else 4)
        if s > 0.05:
            return Mode("fast", chunk=8)          # same weights, fewer steps
        return Mode("milestone_fallback", chunk=4)

class ServingGuard:
    def on_backend_latency(self, p99):
        if p99 > L_MAX:
            self.force_mode("fast")               # admission control
    def watchdog(self, deadline_miss):
        if deadline_miss:
            return last_safe_action()             # never block the control loop
```

### 3.4 与 I6 的分工
- **I6 = 服务工程**：N 端口、独立队列、状态隔离、量化、CUDA Graph、健康探针。
- **I9 = 调度策略**：在给定服务能力下，决定每步花多少计算、开环多长、何时降级/保里程碑。
- 两者共同满足 PR5：任何调度改动都要报告 180s 账与 p99 抖动。
