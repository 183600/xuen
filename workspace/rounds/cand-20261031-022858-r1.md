# 第 13 轮 · PROTO-MEMORY：把 33k 成功演示变成冻结 VLA 的外部记忆，用「快速原型」而不是「更大模型」去打 5 类泛化

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份已核实：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新一轮灵感循环的第 1 轮，也是状态文件里的第 13 次迭代；三个词是「通用机器人」「快速原型」「具身智能」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是把它们收束成一个更可验证的栈：**FACT-VLA 做相位，GEO-RESIDUAL 做几何/接触信号，CHUNK-SERVO 做 5 步执行，MEMORY-VLA 做检索决策，PROTO-LOOP 做快速原型验证。**

## 0. 先说三个会改变判断的新事实

### 0.1 榜单页已改为「即将发布」，29.7% 是 preview JSON，不是真实榜单

截至 2026-10-31，官网首页、排行榜页、运行记录页都显示 **“即将发布 Coming Soon”**；但 `leaderboard_data.json` 仍能返回 8 个模型和 32 维任务分数。上一轮已经证明这份 JSON 是 `gen_leaderboard.py` 生成的：`step ~ success` 回归 R² > 0.999999，成功率不是 10 次 trial 的整数倍（如 27.29%、27.85%、38.43%），详情页视频是占位符。本轮再次确认：**不要把 29.7% 当榜首、当难度表、当失败分布。** 你如果看到“榜首不到 30%”，更准确的说法是“赛事方预览数据的上限约 30%，真实榜单尚未开放”。

这不是坏消息。真实榜单未开放意味着：现在最重要的不是追赶一个不存在的 SOTA，而是**在真实评测开始前，把“快速原型 -> 单任务验证 -> 全量提交”的循环建起来**。这正好对应本轮三个词里的「快速原型」。

### 0.2 提交接口已更新：`obs_delta_indices` + `image_resize`，不是旧的 `data_keys`

当前 `unibot_submission` README（2026-08-21 更新）要求：

- `metadata` 五个字段：`control_space`、`obs_delta_indices`、`image_resize`、`action_chunk_size`、`token`。
- `obs_delta_indices` 同时决定“发哪些观测”和“每路观测堆叠几帧”；`observation.language` 必须是 `[0]`。
- `image_resize` 决定 evaluator 端缩放后的分辨率；不写就保持 480×640；缩放后内参必须按比例缩放。
- 动作仍是 `joint` 或 `ee` 互斥；`ee` 模式返回绝对 EE 位姿（xyz+rpy）+ 2 个 gripper + 7 维 pivot。
- 没有 depth、camera_info、force/torque、tactile；chunk 内没有新观测、没有打断。

这意味着上一轮的 adapter 伪代码要改：不是 `data_keys`/`obs_chunk_size`，而是 `obs_delta_indices`/`image_resize`。**接口工程不是小事；metadata 写错会在握手阶段被拒。**

### 0.3 腕部相机其实有内参；数据动作 schema 和 API 高度同构

上一轮说“腕部相机没有内参矩阵”。本轮逐数据集复核 32 个 `meta/info.json`，发现**全部 32 个数据集**的 `camera_params.wrist_left.color.camera_matrix` 和 `wrist_right.color.camera_matrix` 都在（例如 HangCup 左腕 fx≈436.41, cx≈323.92, cy≈242.93；右腕 fx≈435.12, cx≈319.02），还有畸变系数。这个判断必须修正。

更关键的是：数据集里的 `action.left_ee_pose_gripper_base`、`action.right_ee_pose_gripper_base`、`action.left_gripper`、`action.right_gripper`、`action.pivot`（7 维：vx, vy, angle_z, pivot_3..5, height）与挑战赛 `ee` 动作 schema **几乎一一对应**。这意味着我们可以把 33k 条成功演示直接回放成挑战赛 API 流，不需要先训一个模型。**这是 ProtoLoop 的地基，也是本轮最重要的工程发现。**

## 1. 我从三个词走到了什么

### 1.1 「通用机器人」：不是再训一个更大的通才，而是让一个冻结通才拥有外部记忆

官方已经开源 UnifoLM-WLA-1.0-Base：6B、约 2,500 小时真机、64 个任务（54 桌面 + 10 全身）、MMDiT action expert，且 2026-09-29 加了 LoRA 微调，默认单张 24GB GPU 可跑。再从零训一个 6B/14B 不划算；把官方基座微调一遍也只是“又一个基线”。

真正的通用性缺口在**测试时**：32 个任务各 10 次，5 类泛化各 2 次；模型在训练分布内可能还行，但位置一变、背景一变、物体一换、人一干扰，开环 chunk 就容易崩。人类在同样场景里不是“重新训大脑”，而是**检索过去的相似经验，按当前几何对齐，再微调最后几厘米**。所以本轮把「通用机器人」落成：**一个冻结 VLA + 一个共享的 33k 成功演示记忆 + 一个任务/相位无关的检索-对齐-执行器**。

### 1.2 「快速原型」：先把数据集变成 API，再把 API 变成三级试验台

真实评测要预约、要排队、要烧 320 trials；一次全量评测的机会很贵。上一轮已经有“单任务不计分通道”的策略，但还不够快：你需要一个**在本机就能跑、与官方 API 同构、能在几小时内给出方向**的试验台。

官方 WLA 仓库已经有 `eval_local_episode.py`，能逐 chunk 对比预测动作和真值动作；但它不是挑战赛 API，也不测闭环成功、延迟、泛化和端口隔离。所以本轮提出 **PROTO-LOOP**：

- **Tier 0（小时级）**：把数据集 episode 回放成挑战赛观测/动作流；校验 metadata、shape、dtype、token、延迟；算动作误差、检索命中率、相位进度。
- **Tier 1（天级）**：用官方 MuJoCo/IsaacLab 搭 3 个任务族的轻量风洞；做闭环成功、接触误差、延迟/扰动恢复。
- **Tier 2（周级/稀缺）**：官方不计分单任务通道；5 次 A/B；只验证 Tier 0/1 已经筛过的 3-5 个任务。

这三层不是“再造一个仿真器”，而是**把真机评测变成可复现实验**。Tier 0 一两天能搭起来，Tier 1 一周，Tier 2 只在有把握时烧。

### 1.3 「具身智能」：用机器人自己的身体做几何锚点，而不是再买一个深度相机

API 没有 depth，但机器人有：

- 头部双目已标定（基线 58.25 mm，fx≈282 px，480×640，rectified）；
- 腕部相机有内参（本轮修正）；
- EE 位姿 30Hz 可得；
- 腰部/下身体 15 维可得；
- 4 路 RGB 同时给。

所以「具身智能」不是一句口号，而是：**用头双目做米制深度，用腕部做局部高分辨率对齐，用 EE 位姿做相对目标，用自身运动做视差/主动感知**。检索到的演示轨迹不是绝对坐标，而是“物体->夹爪”的相对位姿；当前物体一动，期望位姿跟着动。这就是第 11 轮 GEO-RESIDUAL 和第 12 轮 DG-KEYFRAME 的延续，但本轮把它接到**外部记忆**上：记忆提供“怎么接触”，几何提供“接触哪里”，VLA 提供“现在该做什么”。

## 2. 诊断：真实瓶颈不是模型不够大，而是“经验不可复用 + 反馈太慢 + 验证太贵”

把一次失败拆成四层：

1. **语义层**：语言理解、任务分解、物体识别。官方 WLA/π0.5/GR00T 已经不错；32 个任务的语言也很短。
2. **几何层**：物体在哪、孔在哪、杯架在哪、夹爪离目标多远。头双目 + 腕部内参可以解决大部分刚体任务；透明/反光/变形仍是难点。
3. **接触层**：最后 3 厘米的插入、挂、叠、拉链、拧。VLA 以 30 步 chunk 开环执行，chunk 内不看新图；远程 RTT 再叠加 50-150ms；接触事件发生在 chunk 内部时，模型只能等下一个 chunk。
4. **经验层**：33k 条成功演示躺在数据集里，当前策略却没有在测试时利用它们。每次失败都从零开始，每个新位置都靠模型参数去泛化，而不是靠“上次类似场景是怎么做的”。

上一轮 CHUNK-SERVO 打的是第 3 层；本轮 MEMORY-VLA 打的是第 4 层；PROTO-LOOP 打的是“验证太贵”。三层叠起来，才是完整的边际收益。

## 3. 本轮押注：PROTO-MEMORY

一句话：

> **把 33k 条成功演示做成冻结 VLA 的外部记忆；测试时按“语言 + 当前视觉 + 相位 + 行为”检索相似片段，用物体/夹爪相对位姿把片段对齐到当前场景，用 5 步视觉伺服执行最后 3 厘米；用三级回放（数据集 API -> MuJoCo 风洞 -> 单任务真机）快速筛掉坏想法。**

三个可验证创新点：

1. **PROTO-LOOP**：数据集到挑战赛 API 的同构回放 + 5 类泛化扰动 + 三级评测；目标是把“想法 -> 结论”的周期从周降到小时/天。
2. **MEMORY-VLA**：冻结 VLA + 非参数演示记忆；检索相位片段，作为动作先验/候选选择/目标位姿；不新增学习模型，不违反单模型规则。
3. **RAP-GA**：检索轨迹的相对位姿对齐；用头双目 + 腕部内参 + EE 位姿，把演示片段从“演示场景”搬到“当前场景”；配合 5 步伺服补最后 3 厘米。

三个词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **通用机器人** | 一个冻结 VLA + 一个共享记忆 + 任务/相位无关的检索器；32 任务不各训模型 | 不从零训 6B/14B；不做 32 个 specialist |
| **快速原型** | 数据集->API 回放；Tier 0/1/2；延迟注入；5 类泛化扰动；单任务 A/B | 不把真机当调试器；不在未过 Tier 0/1 时烧全量 |
| **具身智能** | 头双目深度 + 腕部内参 + EE 相对位姿 + 主动视差；5 步伺服 | 不假设 API 有 depth/force；不做 30Hz 广域网伺服 |

## 4. 创新点清单（本轮排序）

> 详细版见产物区 §3；这里只给“为什么现在做、和现有方案差在哪、能不能落地”。

### P1 PROTO-LOOP（优先级最高，先做）

- **动机**：真实榜单未开放；真机 slot 稀缺；官方 `eval_local_episode.py` 只测动作误差，不测 API/闭环/泛化/延迟。
- **差异**：不是新仿真器，而是“数据集->API 同构回放 + 三级评测”。Tier 0 直接复用数据集的 `action.*_ee_pose_gripper_base`/`action.pivot`，与挑战赛 `ee` schema 对齐。
- **可行性**：高。LeRobot v3 parquet + 视频 + 官方 `example_env.py`；1-2 人 1-2 周。
- **资源**：1-2 名工程师；1 张 GPU（推理）；16-32 CPU；1-2 TB 存储；不需要真机。
- **步骤**：解析数据集 -> 构造 obs/action -> 用官方 client 校验 -> 加延迟/扰动 -> 加 Tier 1 风洞 -> 输出报告。
- **风险**：离线动作误差≠真机成功率；视频解码慢；仿真 gap。缓解：Tier 0 只做筛选，Tier 1/2 做确认。

### P2 MEMORY-VLA（核心增量）

- **动机**：33k 成功演示是现成的“经验库”；5 类泛化要求测试时适应；单模型规则禁止再加一个学习策略。
- **差异**：检索是数据，不是模型；用 VLA 自己的视觉特征或经典描述子；检索到的片段只作为先验/候选/目标，不替代 VLA 的语义规划。
- **可行性**：中高。30 万-60 万关键帧；FAISS/HNSW；<1GB；检索 <10ms。
- **资源**：1-2 张 GPU；1 名工程师 4-6 周；存储 <1TB（关键帧）。
- **步骤**：相位分割 -> 关键帧 -> 嵌入 -> 索引 -> 离线命中率 -> 对齐 -> 集成 -> A/B。
- **风险**：检索 mismatch；分布外物体；单模型解释；延迟。缓解：任务/相位过滤、几何校验、置信度回退、用 VLA 编码器。

### P3 RAP-GA（MEMORY-VLA 的几何对齐器）

- **动机**：检索到的轨迹是演示场景的绝对坐标；位置/物体一变就失效。
- **差异**：用“物体->夹爪”相对位姿对齐，而不是绝对轨迹；头双目 + 腕部内参 + EE 位姿；透明/变形回退到起点相对对齐。
- **可行性**：中。刚体任务可做；透明/反光/变形难。
- **资源**：1 名工程师 3-4 周；标定工具；分割/位姿估计（可用经典几何，不一定是第二个学习模型）。
- **步骤**：离线估计物体/受器位姿 -> 计算相似变换 -> 应用到检索轨迹 -> 置信度融合 -> 真机验证。
- **风险**：位姿误差、遮挡、标定漂移。缓解：多帧估计、ROI 局部对齐、置信度低回退 VLA。

### P4 RAP-SELECT（便宜的测试时计算）

- **动机**：生成式 VLA 可以采样多个 chunk；选一个好的比再训一个模型便宜。
- **差异**：用“检索一致性 + 动作平滑 + gripper 时序”选候选；不做学习 critic；用 medoid 作为无检索时的基线。
- **可行性**：高（如果 WLA 支持多 seed 采样）；延迟 2-4 倍。
- **资源**：1 张 GPU；1 名工程师 2-3 周。
- **步骤**：采样 K=4-8 -> 打分 -> 选 -> 测延迟/成功率 -> 消融。
- **风险**：延迟、候选多样性不足、分数与成功不相关。缓解：只在接触相位开；K 自适应；与检索结合。

### P5 AXIS-CURRICULUM（5 类泛化的数据课）

- **动机**：5 类泛化各 2/10，占 20%；训练数据大概率偏背景/位置。
- **差异**：从演示生成轴特定扰动（位置、干扰物、背景、未见物体、人手），做 LoRA 微调 + 轴平衡采样；不是盲目的图像增强。
- **可行性**：中。2D 增强不能完全替代 3D 变化；但能提升视觉鲁棒性。
- **资源**：1-2 GPU 周；数据管线；1 名工程师 4 周。
- **步骤**：扰动生成 -> 轴平衡 -> LoRA -> 离线/仿真 -> 真机。
- **风险**：合成伪影、3D 物理不真、过拟合。缓解：只用它做“鲁棒性正则”，不指望它解决接触。

### P6 WESC + 主动视差（具身智能的补丁）

- **动机**：腕部有内参但缺外参；透明/反光物体深度不稳。
- **差异**：用演示的 EE 位姿 + 腕部图像做手眼标定；抓取前做 1-3 秒小范围腕部/头部运动，用视差补深度。
- **可行性**：高（标定）；中（主动视差）。
- **资源**：1 名工程师 1-2 周；标定板；无需新数据。
- **步骤**：AX=XB 标定 -> 重投影验证 -> 主动视差策略 -> 单任务测试。
- **风险**：标定漂移、运动扰动场景、时间预算。缓解：每机器人一次校准；只在低置信度时触发；限幅。

### 剪枝（本轮明确不做）

- 不从零训 VLA/World Model：官方 WLA + LoRA 已经够便宜。
- 不做完整 sim-to-real 策略训练：只做控制器/接口风洞。
- 不做 30Hz 广域网伺服：RTT 不允许；用 5 步 chunk。
- 不做逐任务 specialist：规则禁止，且不泛化。
- 不做 6D 物体位姿网络作为唯一方案：透明/变形不可靠；用相对位姿 + 局部特征。
- 不做力/触觉闭环：API 没有。
- 不把 preview JSON 的任务排名当难度表：已证伪。

## 5. 与第 10-12 轮的关系：保留、升级、剪枝

**保留**：

- FACT-VLA 的相位化 BC / 自动相位；

**升级**：

- 从“单模型开环”升级到“冻结模型 + 非参数记忆 + 确定性伺服”；

- 从“腕部无内参”修正为“腕部有内参，只需外参标定”。

**剪枝**：

- 上一轮把“视觉伺服”作为主投；本轮把“检索 + 对齐”作为主投，伺服降为执行层；

- 上一轮假设榜单 29.7% 是 preview；本轮确认榜单页已改为 Coming Soon，策略从“追榜”改为“抢先建立可复现原型”。

# 第 13 轮产物 · PROTO-MEMORY 技术报告

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「PROTO-MEMORY」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是把它们收束成“记忆 -> 对齐 -> 执行 -> 验证”的栈。

## 0. 结论与边界

### 0.1 一句话结论

截至 2026-10-31，真实榜单尚未开放，29.7% 只是 preview JSON 的上限；此时最大的边际收益不是再训一个更大的 VLA，而是**把 33k 条成功演示做成冻结 VLA 的外部记忆，用相对位姿把检索片段对齐到当前场景，用 5 步视觉伺服补最后 3 厘米，并用“数据集 API 回放 -> MuJoCo 风洞 -> 单任务真机”三级原型把每次评测变成可复现实验**。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、排行榜 JSON 直接核实 | 规则、API schema、33,276 eps、腕部内参、WLA LoRA |
| B | 我们在公开数据/网页上做的分析，可复现 | preview JSON 的 `step ~ success` 回归、任务时长统计、任务名映射 |
| C | 设计假设，需 G0-G7 验证 | 检索涨点、对齐误差、5 步伺服稳定域、单模型合规解释 |

### 0.3 本轮不做什么

- 不从零训 VLA/World Model；官方 WLA 已开源 6B 基座和 LoRA。
- 不做完整 sim-to-real 策略训练；数字孪生只做控制器/接口风洞。
- 不做第二个学习策略/残差网络；检索是数据，伺服是确定性控制器。
- 不做 30Hz 广域网伺服；用 5 步 chunk/双频执行。
- 不做 32 个任务各一个 specialist；规则禁止，且不泛化。
- 不做 6D 物体位姿网络作为唯一方案；透明/变形不可靠，用相对位姿 + 局部特征。
- 不做力/触觉闭环；API 没有。
- 不把 preview JSON 的任务排名当真实难度表；只当先验。

## 1. 事实核对

### 1.1 榜单状态：preview JSON 与 Coming Soon 并存（A+B）

2026-10-31 复核：

- 官网首页、`leaderboard.html`、`runs.html` 均显示 **“即将发布 Coming Soon”**。
- `leaderboard_data.json` 仍返回 8 个模型和 32 维任务分数；字段 `generated_from` 是 `"gen_leaderboard.py"`。
- 8 个模型的总平均成功率分别为：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、PI-0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。
- 每任务只有 10 次 trial，但 JSON 中成功率出现 27.29%、27.85%、38.43% 等非 10% 整数倍；真实 10 次 trial 只能是 0/10、1/10、…、10/10。
- 详情页 `details.html?model=...&task=...` 仍是“测试视频占位，后续可替换为真实视频文件”。
- 上一轮对 8 个模型 ×32 任务做 `step_score ~ success_rate` 回归，R² > 0.999999，最大残差 <0.006；这不是实测步骤分，是脚本生成的线性缩放。

**结论**：29.7% 只能作为“赛事方预览上限/难度信号”；不能作为 SOTA、任务难度表、失败分布。真实榜单未开放意味着现在是建立快速原型和基线的时间窗口。

### 1.2 规则（A）

官方参赛手册（2026-10-31 通过 `r.jina.ai` 重新抓取中文版；§1.1-§2.2 稳定）核实：

| 项 | 规则 |
|---|---|
| 模型 | 所有任务须基于**同一模型**完成，不得混合多个模型一起测试；模型类型不限（World Model、VLA 均可） |
| 任务 | 32 项桌面任务 |
| 次数 | 每任务 10 次独立运行 |
| 泛化 | 5 类各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰 |
| 时限 | 单次真机执行上限 **180 s**；超时记为失败，并按执行情况计算步骤分 |
| 排名 | 先比 32 任务总平均成功率；相同看总平均步骤分；再相同看更早提交 |
| 部署 | 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态必须隔离 |
| 测试通道 | 另有**不计分的单任务测试通道**，可测 1 个任务的成功率/步骤分，不计入排行榜 |

**对方案的约束**：PROTO-MEMORY 必须每端口独立、CPU 轻量、不抢 GPU；VLA 是唯一学习策略；检索是数据/非参数记忆；伺服是确定性控制器；单任务通道是唯一敢做 A/B 的地方。

### 1.3 提交 API（A）

当前 `unibot_submission` README（2026-08-21 更新，2026-10-31 复核）给出：

| 项 | 规格 |
|---|---|
| `metadata` | `control_space`、`obs_delta_indices`、`image_resize`、`action_chunk_size`、`token` 五个字段 |
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB 480×640 |
| 本体 | 双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str` |
| 动作空间 | `joint` 或 `ee` 互斥 |
| 共享动作 | `action.left_gripper [1]`、`action.right_gripper [1]`、`action.pivot [7]` |
| EE 动作 | `action.left_ee_pose_gripper_base [6]`、`action.right_ee_pose_gripper_base [6]`（绝对目标位姿，xyz+rpy，base 系） |
| chunk | `action_chunk_size` ≥1 固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action` |
| token | `metadata.token` 握手校验一次；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile** |
| 监控 | 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分 |

**关键推论**：`action_chunk_size=30`、控制频率 30Hz 时，一次 `get_action` 之后有 **1 秒开环执行**；chunk 内没有新观测，也没有打断机制。视觉伺服要生效，必须把 chunk 降到 3-8 步，或把 VLA 规划与伺服执行拆成双频。

### 1.4 数据集规模、相机与动作 schema（A）

32 个 HF 数据集（2026-10-31 通过 `meta/info.json` 逐一读取并求和）：

| 项 | 数值 |
|---|---:|
| episodes | **33,276** |
| frames | **18,282,246** |
| 时长 | **169.28 h**（30 fps） |
| 任务数 | 32 |
| 单任务 episodes | 969-1,533 |
| 单任务平均时长 | 6.2 s（HangCup）-37.6 s（ToolboxStorage） |

关键相机事实：

- 头双目：`head_stereo_left/right` 480×640，已 rectified；HangCup 左目 `fx≈282.37, fy≈282.75, cx≈311.53, cy≈256.63`；右目 `fx≈281.87, fy≈282.32, cx≈329.96, cy≈249.51`；基线 **58.2526 mm**。
- 腕部：**全部 32 个数据集**的 `wrist_left/right.color.camera_matrix` 存在（本轮修正上一轮“无内参”的判断）。HangCup 左腕 `fx≈436.41, fy≈435.92, cx≈323.92, cy≈242.93`；右腕 `fx≈435.12, fy≈434.50, cx≈319.02, cy≈240.99`；带 Brown-Conrady 畸变。
- `state_d435` 是头相机在 base 系的 6D 位姿；`waist_state_joint = lower_body[-3:]`；线上 API 给 `lower_body`，头相机外参可在线路恢复。
- 数据集视频是 AV1 480×640 30fps；Tier 0 回放要算解码成本。

**动作 schema**：数据集与挑战赛 `ee` API 高度同构。第一帧 HangCup 示例：

```text
observation.state.left_ee_pose_gripper_base  = [0.3014, 0.2768, 0.0662, 0.0028, 0.3865, -0.1991]
observation.state.right_ee_pose_gripper_base = [0.2555, -0.2781, 0.0996, 0.0196, 0.3182, 0.3690]
action.left_ee_pose_gripper_base             = [0.3067, 0.2797, 0.0782, 0.0336, 0.3477, -0.1886]
action.right_ee_pose_gripper_base            = [0.2579, -0.2779, 0.1086, 0.0044, 0.2860, 0.3704]
action.left_gripper                          = 4.5
action.right_gripper                         = 4.4786
action.pivot                                 = [0.0, 0.0, -0.0, 0.0, 0.15, 0.0, 0.74]
```

注意三点：

1. `action.*_ee_pose_gripper_base` 是**绝对目标位姿**，与 API `ee` 动作直接对应；这意味着 Tier 0 回放不需要先训模型。
2. gripper 动作是**原始命令值**（示例约 4.5），不是 0-1；API 的 gripper 范围/方向必须用官方 `example_env.py` 和单任务通道校验。
3. `action.pivot` 7 维名称是 `vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height`；`pivot_3..5` 的语义 README 没有逐维定义，必须用 `example_env.py`/单任务通道验证；不要猜符号。

### 1.7 preview 榜单头部的模型家族与瓶颈（A+B，分数不作为真实结果）

| 模型家族 | 公开路线 | 优势 | 与本轮相关的瓶颈 |

| **DM0** | Embodied AI Institute；公开技术细节有限 | 可能是 VLA/世界模型混合 | 任务特定精度；数据覆盖 |
| **π0.5** | Physical Intelligence 的开放世界泛化 VLA | 语义/新场景泛化 | 接触密集任务的精度；远程部署延迟 |
| **GigaBrain-0** | 世界模型生成数据 + VLA；用世界模型降真机数据依赖 | 数据效率/泛化 | 生成数据的物理保真度；最后 3 厘米 |
| **GR00T N1.5** | NVIDIA 通用人形 VLA | 生态/embodiment | 任务特定精度；数据覆盖 |

共同点：

- 都是 action chunk 开环执行；chunk 内不看新图。
- 模型越大，chunk 越长，越不反应；长 chunk 与接触精度直接冲突。
- 世界模型解决“想象未来”，不解决“现在偏了 2mm”。
- 单模型规则让“再加一个学习残差”危险；但“检索 + 确定性伺服”不是第二个策略模型。

### 1.8 近期工作：检索增强与快速原型都在 2026 年成为活跃方向（A）

| 工作 | 与本轮的关系 | 关键结论/提醒 |
|---|---|---|
| **RA-VLA**（arXiv:2608.25585，ICML 2026） | 行为对齐检索 + 上下文遵循损失 | LIBERO +17.60pp、UR5e +20.83pp；推理延迟几乎不随检索段数增长 |

| **ReCAP**（arXiv:2606.15631） | 检索条件动作策略；冻结策略，新任务靠加池 | PushT 34.9% vs 6.0%；RoboTwin 2.0 31.5% vs 26.0% |
| **ICI-VLA**（arXiv:2609.07581） | 上下文模仿；DTW 对齐 + Target Action Masking | LIBERO 97.7%、RoboTwin 2.0 60.4% |

| **When Does Retrieval Help?**（arXiv:2610.05492） | 系统比较检索方法 | 没有一种检索方法始终最好；随机检索也有非平凡成功率；检索质量指标不能可靠预测下游表现 |

| **XPolicyLab**（arXiv:2608.09892） | 统一策略/环境适配标准 | O(N+M) 集成；42 个策略 |
| **Nautilus**（arXiv:2605.11665） | agentic 机器人学习 harness | 从一句 prompt 到复现/评测/微调/部署 |

**战略含义**：检索增强 VLA 是 2026 年的前沿，但“检索不是免费午餐”——需要几何对齐、置信度门控和严格 A/B。PROTO-MEMORY 的差异不是“再加一个检索模块”，而是**把检索接到 33k 条同 embodiment、同任务、同动作 schema 的成功演示上，并用三级原型验证**。这是挑战赛特有的数据优势。

### 1.9 未核实/未解决

- 评测端实际控制频率（本报告假设 30Hz；必须实测）。
- 网络 RTT 分布（同城/跨城/跨洲；必须实测）。
- 腕部相机外参（内参已有；外参仍缺；需手眼标定）。
- 线上 API 的四路 RGB 是否与数据集同源/同标定（头双目是否仍 rectified）。

## 2. 问题形式化

### 2.1 评分与不确定性

总分：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

320 trials 下，若 `p≈0.25`，单次标准误：

```math
\mathrm{SE}(S)\approx \sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

配对 A/B 的方差取决于任务内相关；若同一初始条件的 A/B 成功高度相关，配对差值方差可显著降低。报告必须给配对差值的 bootstrap 置信区间，而不是只报两个平均值。

人为干扰轴：

```math
\Delta S_{\mathrm{human}} = \frac{2}{10}\,\Delta p_h = 0.2\,\Delta p_h.
```

即 human 轴成功率 +10pp → 全局 +2pp（每个任务 10 次里 2 次是 human；32 任务平均后仍为 0.2 倍）。

### 2.2 接口时间模型

设：

- `f_c`：evaluator 控制频率（假设 30Hz）；
- `H_c`：提交的 `action_chunk_size`；
- `τ`：网络 RTT + 推理 + 图像传输的等效延迟；
- `T_fb`：从“世界变化”到“策略看到变化”的反馈周期。

则：

```math
T_{\mathrm{fb}} \approx \frac{H_c}{f_c} + \tau.
```

| 场景 | `H_c` | `f_c` | `τ` | `T_fb` | 评价 |
|---|---:|---:|---:|---:|---|
| 官方 WLA 默认 | 30 | 30 | 50ms | **1050ms** | 接触段基本开环 |
| 本方案保守 | 5 | 30 | 50ms | **217ms** | 可做 1-2 次接触修正 |
| 本方案乐观 | 5 | 30 | 20ms | **187ms** | 需低 RTT |
| 本方案高延迟 | 5 | 30 | 150ms | **317ms** | 增益降档 |
| 低控制频率 | 5 | 10 | 50ms | **550ms** | 改 `H_c=3` 或只做 PBVS |
| 极低延迟 | 3 | 30 | 20ms | **120ms** | 动态任务可用 |

**结论**：`H_c` 必须按实测 `f_c` 和 `τ` 选；不能把 30 步默认值直接搬到远程 API。

### 2.3 记忆检索的形式化

定义演示记忆：

```math
\mathcal{M}=\{(e,k,\mathbf{z}_{e,k},\pi_{e,k},\mathbf{g}_{e,k})\},
```

其中：

- `e`：episode；
- `k`：关键帧；
- `z`：视觉/几何描述子；
- `π`：关键帧之后的动作片段（EE 绝对位姿、gripper、pivot）；
- `g`：几何/行为特征（物体相对位姿、EE 相对位姿、gripper 开合、双臂角色）。

查询 `q = (o_t, l, phase_t, history_t)`。检索分数：

```math
s(q,m)=
w_v\cos(\mathbf{z}_q,\mathbf{z}_m)
+w_l\,\mathbb{1}[l_q=l_m]
+w_p\,\mathbb{1}[\phi_q=\phi_m]
+w_g\exp\!\left(-\frac{\|\mathbf{g}_q-\mathbf{g}_m\|^2}{2\sigma^2}\right)
-w_b\,\mathrm{DTW}(\mathbf{h}_q,\mathbf{h}_m).
```

- `φ`：FACT-VLA 相位（reach/grasp/transport/insert/release）；
- `h`：最近 5-10 步的 EE 轨迹/夹爪历史；
- `w_*`：离线标定的权重，不做在线学习。

取 top-k（k=5），再做几何一致性重打分。**任务/相位过滤优先于外观**，避免“插网线”匹配到“拔网线”。

### 2.4 相对位姿对齐

记 `T_a^b` 为坐标系 b 在坐标系 a 中的位姿。对记忆关键帧 `m`：

```math
T_o^e(m) = \left(T_b^o(m)\right)^{-1} T_b^e(m).
```

查询时物体位姿为 `T_b^o(q)`，则期望 EE 位姿：

```math
T_b^{e,d}(t) = T_b^o(q)\,T_o^e(m)\quad\text{（单点）},
```

```math
T_b^{e,d}(t) = T_b^o(q)\left(T_b^o(m)\right)^{-1}T_b^e(m,t)\quad\text{（整段）}.
```

若物体位姿不可用，用起点相对对齐：

```math
T_b^{e,d}(t) = T_b^e(q,0)\left(T_b^e(m,k)\right)^{-1}T_b^e(m,t).
```

两者按置信度 `β` 在 SE(3) 上融合：

```math
T_{\mathrm{align}} = \exp\left((1-\beta)\log T_{\mathrm{start}} + \beta\log T_{\mathrm{obj}}\right),
```

```math
T_b^{e,d}(t)=T_{\mathrm{align}}T_b^e(m,t).
```

- `β=0`：只信起点相对；
- `β=1`：只信物体相对；
- `β` 由物体位姿协方差、可见性、重投影误差决定。

为什么用相对目标：

- **位置泛化**：物体移动 → `T_b^o(q)` 变 → 期望位姿跟着变。
- **人为干扰**：人移动物体 → 重新估计 → 期望位姿跟着变。
- **未见物品**：只要受器/任务几何不变，相对目标不变；外观由 VLA 处理。
- **背景/干扰物**：伺服只用局部 ROI/目标图，不依赖全局背景。

### 2.5 候选选择与伺服

生成式 VLA 可以采样 K 个动作 chunk。对每个候选 `a_i`，用检索片段 `r_j` 打分：

```math
S(a_i)=-\min_j \mathrm{DTW}(a_i,r_j)
-\lambda_s\|\Delta a_i\|^2
-\lambda_g|t^{\mathrm{close}}_i-t^{\mathrm{close}}_{\mathrm{ref}}|.
```

- 若最高分与次高分差小于阈值，选 medoid（对 K 个样本的逐维中位数），避免过拟合检索。
- 只在接触相位开候选选择；远距离用单样本，省延迟。
- 伺服误差：

```math
e(t)=\log\left(T_b^e(t)^{-1}T_b^{e,d}(t)\right),
```

```math
a_{\mathrm{cmd}} = a_{\mathrm{ff}}\circ\exp\left(\mathrm{clip}(K_p e+K_d\dot e,\pm\delta_p,\pm\delta_r)\right).
```

- `a_ff`：VLA 的前馈动作；
- `δ_p`：每块最多 1cm；`δ_r`：每块最多 0.05rad；
- 接触段法向缩幅/低通，切向保留；
- 延迟补偿：`e_{t+τ} ≈ e_t + J_v v τ`；增益按 `τ/H_c` 降档。

### 3.2 P1 · PROTO-LOOP

**动机**：真实榜单未开放；真机 slot 稀缺；官方 `eval_local_episode.py` 只做动作对比，不测 API 合规/闭环/泛化/延迟/端口隔离。没有快速原型，所有想法都只能靠“等真机”验证，迭代速度被锁死。

**与现有方案的差异**：

- 不是再造一个仿真器，而是**数据集到挑战赛 API 的同构回放**：数据集的 `action.*_ee_pose_gripper_base`/`action.pivot`/gripper 与 API `ee` schema 对齐，Tier 0 可以不改模型就跑通。
- 不是只测 MSE，而是三层指标：API 合规、动作/相位、闭环成功。
- 不是随机图像增强，而是按 5 类泛化轴生成扰动。

**技术可行性**：高。LeRobot v3 parquet + AV1 视频 + 官方 `example_env.py`；Tier 0 可在 1-2 天搭出最小版本；Tier 1 用官方 MuJoCo/IsaacLab 搭 3 个任务族，1 周。

**所需资源**：

- 数据：32 个 HF 数据集（只读）；关键帧缓存 100-300GB。
- 算力：1 张 GPU 做策略推理；16-32 CPU 做视频解码/回放；1-2TB 存储。
- 接口：官方 `unibot_submission` 的 `PolicyService`/`example_env.py`；不需要真机。

**落地步骤**：

1. 解析 `meta/info.json` + `data/*.parquet` + `videos/*.mp4`；建立 episode→task→language 映射。
2. 写 `DatasetToAPIAdapter`：把 `head_stereo_left/right`→`cam_left/right_high`，`wrist_left/right`→`cam_left/right_wrist`；状态/动作按 API 键映射；gripper/pivot 先原样，后续校验。
3. 写 `MockEvaluator`：复用 `example_env.py` 的 metadata/action 校验；注入 RTT/jitter；记录 p50/p95/p99。
4. 写 `ActionMetrics`：平移 MAE（mm）、旋转 MAE（deg）、gripper 时序误差、DTW、jerk。
5. 写 `PerturbationSuite`：位置/干扰物/背景/未见物/人手；先做 2D，后做 3D/仿真。
6. 写 `Tier1WindTunnel`：3 个任务族（peg-in-hole、hang/stack、zip/unlock）；50 trials/组合。
7. 输出 `protoloop_report.json`：每个想法的合规率、动作误差、延迟、检索命中、仿真成功、建议是否进 Tier 2。

**风险**：

- 代理指标与真机成功率不相关：用 Tier 1/2 校准；Tier 0 只做筛除，不做最终结论。
- 视频解码慢：预解码关键帧/降采样；用 `decord`/PyAV 并行。
- 数据集动作与线上 API 不完全同源：gripper 范围、pivot 语义、头双目是否 rectified；用单任务通道校验。
- 数据泄漏：离线检索评估按 episode/session 分组，查询 episode 不参与检索库。

### 3.3 P2 · MEMORY-VLA

**动机**：33k 条成功演示是现成的“经验库”；5 类泛化要求测试时适应；单模型规则禁止再加一个学习策略。检索是数据，不是模型；它可以在不更新参数的情况下把“上次类似场景怎么接触”搬过来。

**与现有方案的差异**：

- 不是 RAG 式“把演示塞进 prompt”（VLA 上下文长度/延迟不允许），而是**检索动作片段 + 几何对齐 + 执行层跟踪**。
- 不是第二个策略/残差网络；检索器不输出动作，只提供参考轨迹/目标位姿/候选评分。
- 不是只按图像相似度检索；用任务/相位/行为/几何多因子，避免“看起来像但动作不对”。

**技术可行性**：中高。

- 关键帧：每 episode 10-20 个 → 33k×10-20 ≈ 33-66 万；用 256-d float16，约 170-340MB；FAISS/HNSW <1GB。
- 检索延迟：CPU 上 top-50 + 重打分 <10ms；与 VLA 推理并行。
- 视觉描述子：优先用 WLA 自己的视觉编码器（同一 checkpoint，合规）；退路是 ORB/颜色/几何描述子（无学习权重）。
- 动作片段：数据集的 EE 绝对位姿/gripper/pivot 直接可用；对齐后转 API。

**所需资源**：

- 1-2 张 GPU（编码 + VLA 推理）；1 名工程师 4-6 周；存储 <1TB（关键帧/索引）。
- 数据：32 个任务全集；离线标注/相位分割可用 FACT-VLA 或启发式。

**落地步骤**：

1. 相位分割：gripper 开合、EE 速度、接触距离、任务模板；先做 5 个代表任务。
2. 关键帧选择：pre-grasp、grasp、transport、pre-insert、insert、release。
3. 描述子：VLA 视觉特征（PCA 到 256）+ 几何/行为特征（EE 相对位姿、gripper、物体尺寸）。
4. 建索引：按 task/phase 分片；每片 HNSW/IVF；元数据存动作片段/位姿/质量分。
5. 离线评估：留一 episode；top-5 命中率、对齐后动作误差、DTW。
6. 集成：`get_action` 里检索→对齐→与 VLA plan 融合→伺服；置信度低回退 VLA。
7. A/B：VLA-only vs VLA+memory；5 任务×5 次；配对 bootstrap。

**风险**：

- 检索 mismatch：任务/相位过滤 + 几何校验 + 置信度门控；低置信度回退。
- 分布外物体：检索按形状/affordance，不按语义；透明/变形回退 VLA。
- 单模型解释：检索器用同一 VLA 编码器或经典描述子；提交材料写清楚。
- 延迟：预计算索引；检索与 VLA 并行；只在接触相位开候选选择。
- 数据泄漏：离线评估按 episode 分组；不要把查询 episode 放进检索库。

### 3.4 P3 · RAP-GA

**动机**：检索到的轨迹是演示场景的绝对坐标；位置/物体一变就失效。需要把“演示轨迹”变成“当前场景的轨迹”。

**与现有方案的差异**：

- 不是绝对轨迹回放；是“物体→夹爪”相对位姿对齐。
- 不是 6D 物体位姿网络；刚体用头双目 + 局部 ICP/平面/圆拟合；透明/变形回退起点相对。
- 不是只对齐起点；用物体位姿对齐整段，保留接触相位。

**技术可行性**：中。

- 刚体受器（杯架、网口、试管架、锁孔）可用头双目 + 边缘/圆/线拟合；不需要学习模型。
- 腕部内参已有（本轮修正）；外参用手眼标定（WESC）。
- 透明/反光/变形任务（FoldTowel、PackBag）不启用精确对齐，只用 VLA/相位。

**所需资源**：

- 1 名工程师 3-4 周；标定板；分割/几何工具（OpenCV/Open3D）；无新数据。
- 算力：CPU 即可；深度图/点云局部处理 <10ms。

**落地步骤**：

1. 离线：对 5 个代表任务标定物体/受器 ROI；用头双目生成局部点云。
2. 估计 `T_b^o`：平面/圆/线/ICP；输出协方差/置信度。
3. 计算 `T_align`；应用到检索轨迹；转 API 绝对 EE。
4. 置信度融合：`β` 由重投影误差/可见性/深度有效像素决定。
5. 回退：物体位姿不可靠 → 起点相对对齐 → VLA 开环。
6. 验证：离线重投影/动作误差；Tier 1 接触误差；Tier 2 单任务。

**风险**：

- 位姿误差：多帧估计、ROI 局部对齐、置信度门控。
- 遮挡：腕部/头部切换；目标被夹爪挡住时用起点相对。
- 标定漂移：每机器人一次重投影校准；误差大关伺服。
- 透明/反光：不硬做；回退 VLA。

### 3.5 P4 · RAP-SELECT

**动机**：生成式 VLA 可以采样多个 chunk；选一个好的比再训一个模型便宜。WLA 是 flow/diffusion，多 seed 采样是现成的测试时计算。

**与现有方案的差异**：

- 不做学习 critic；用检索一致性 + 动作平滑 + gripper 时序。
- 不总是开；只在接触相位/低置信度时开，控制延迟。
- 用 medoid 作为无检索基线，避免“检索错了还自信”。

**技术可行性**：高（若 WLA 支持多 seed；否则用 dropout/温度扰动）。延迟 2-4 倍，需要批处理。

**所需资源**：1 张 GPU；1 名工程师 2-3 周；Tier 0/1 评估。

**落地步骤**：

1. 确认 WLA 采样接口：多 seed/多噪声/多温度。
2. 采样 K=4-8；记录延迟。
3. 打分：DTW 到检索片段、jerk、gripper 时序；选 top-1 或 medoid。
4. 消融：K=1/2/4/8；检索 on/off；接触相位 on/off。
5. 门：成功率 +5pp 且 p99 延迟不超预算，否则只在离线用。

**风险**：延迟、候选多样性不足、分数与成功不相关。缓解：自适应 K、批处理、只在接触相位开、用 Tier 1 校准分数。

### 3.6 P5 · AXIS-CURRICULUM

**动机**：5 类泛化各 2/10，占 20%；训练数据大概率偏背景/位置。模型对背景/干扰物/未见物的鲁棒性不能只靠 WLA 基座。

**与现有方案的差异**：

- 不是随机图像增强；是按 5 个轴生成有语义的扰动。
- 不是全参数微调；用 LoRA（官方已支持）做轻量适配。
- 不是指望合成数据解决接触；只做视觉/语义鲁棒性正则。

**技术可行性**：中。

- 位置：3D 变换/图像 homography；需要深度/物体 mask。
- 干扰物：2D copy-paste + 阴影；仿真里加物体。
- 背景：分割/	inpainting 换桌布/纹理。
- 未见物：换纹理/形状保持的物体；仿真里用 held-out 物体。
- 人手：叠加人手/手臂视频；仿真里脚本化移动物体。

**所需资源**：1 名工程师 4 周；1-2 GPU 周 LoRA；数据管线；存储。

**落地步骤**：

1. 选 5 个代表任务；生成每轴 500-1000 个变体。
2. 轴平衡采样；LoRA action head（先不改 VLM）。
3. 离线/Tier 1 评估；只看轴内提升，不看平均。
4. 若有效，扩到 32 任务；若无效，剪枝。

**风险**：合成伪影、3D 物理不真、过拟合。缓解：只做正则；Tier 1/2 确认；不替代检索/伺服。

### 3.7 P6 · WESC + 主动视差

**动机**：腕部有内参但缺外参；透明/反光物体深度不稳。主动视差可以在不增加硬件的情况下补深度。

**与现有方案的差异**：

- 用演示的 EE 位姿 + 腕部图像做手眼标定（AX=XB），不需要额外标定设备。
- 抓取前做 1-3 秒小范围腕部/头部运动，用视差补深度；不是被动等待深度相机。
- 只在低置信度时触发；限幅/限速，避免扰动场景。

**技术可行性**：高（标定）；中（主动视差）。

**所需资源**：1 名工程师 1-2 周；标定板；无需新数据。

**落地步骤**：

1. 采 20-50 组腕部图像 + EE 位姿；解 AX=XB。
2. 重投影验证 ≤5px；否则只用头双目。
3. 主动视差：腕部旋转 5-10°，取 3-5 帧；光流/特征跟踪估计深度。
4. 只在透明/反光/低置信度触发；时间预算 ≤3s。
5. 单任务测试；不影响主流程。

**风险**：标定漂移、运动扰动、时间预算。缓解：每机器人一次校准；只在低置信度触发；限幅；失败回退。

## 4. 系统设计

### 4.1 三层架构

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)       │
                    │  ├─ FACT-VLA phase observer         │
                    │  ├─ GEO-RESIDUAL contact/edit       │
                    │  ├─ MEMORY retrieval + RAP-GA       │
                    │  ├─ RAP-SELECT candidate scoring    │
                    │  ├─ CHUNK-SERVO 5-step executor     │
                    │  └─ action adapter (WLA 54D → API)  │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared VLA server (GPU)            │
                    │  UnifoLM-WLA-1.0 / LoRA, 30-step    │
                    └─────────────────────────────────────┘
```

- 每个端口一个 `PolicyService` 实例，独立 `reset()`、独立 plan cache、独立 retrieval history、独立 servo state。
- 检索/伺服是 CPU 线程，不阻塞 websocket；VLA 请求异步、可批处理。
- 共享 VLA server 用 session ID 区分端口；模型权重只有一份，不违反单模型。
- GPU 6B bf16 约 12GB；一张 24GB/40GB GPU 可服务多个端口，具体并发取决于 batch 和序列长度。

### 4.2 数据流

```text
离线（一次）:
  32 tasks × 1k episodes
    → phase segmentation
    → keyframes
    → visual/behavior descriptors
    → memory index (task/phase shards)
    → object/EE relative poses
    → wrist target images (optional)

在线（每 episode）:
  obs_t
    → FACT-VLA phase
    → MEMORY retrieval (top-k)
    → RAP-GA alignment
    → VLA plan (async, 30-step)
    → RAP-SELECT (optional, contact phase)
    → CHUNK-SERVO (5-step)
    → API action chunk
```

### 4.3 记忆库结构

```text
memory/
  tasks.jsonl                 # task_id, language, aliases
  index/
    <task_id>_<phase>.faiss   # HNSW/IVF, 256-d float16
  segments/
    <segment_id>.npz          # actions (H,21), object pose, EE pose,

```

规模估算：

- 33k episodes × 10-20 keyframes = 33-66 万段；

- 动作片段 30×21 float32 ≈ 2.5KB/段 → 0.8-1.6GB（可只存关键相位，降到 <500MB）；
- 腕部目标图 128×128 JPEG ≈ 5-10KB → 1.6-6.6GB（可选，先不存全量）；
- 索引/元数据 <1GB；总 <3GB（不含可选图像）。

- 其余键先用 `[0]` 取当前帧；若 WLA 训练配置要求多帧堆叠，改成 `[-4,-2,0]` 等，保持 offset ≤0、严格递增。

- 图像映射为 `cam_left_high` + 左右腕部三路；`cam_right_high` 只用于双目深度/伺服。
- 语言：WLA server 用 `unnorm_key`/固定 prompt，不直接吃挑战赛的 `observation.language`；需要把 32 任务语言映射到 WLA 的任务 key（或空 prompt），并在单任务通道验证。

**动作返回（`ee` 模式）**：

```python
{
    "meta.token": token,
    "action.left_gripper":  np.float32 (5,1),
    "action.right_gripper": np.float32 (5,1),
    "action.pivot":         np.float32 (5,7),
    "action.left_ee_pose_gripper_base":  np.float32 (5,6),  # absolute xyz+rpy
    "action.right_ee_pose_gripper_base": np.float32 (5,6),  # absolute xyz+rpy
}
```

**动作适配（WLA 54D → 挑战赛 21D）**：

1. `left_ee_abs = compose(T_base_ee_left_current, exp(left_ee_rel))`；转 xyz+rpy。
2. `right_ee_abs` 同理。
3. gripper 直通（按挑战赛的原始范围/方向校验；数据示例约 4.5，不是 0-1）。
4. `pivot = [vx, vy, wz, pivot_3, pivot_4, pivot_5, height]`，从 WLA base/waist/height 组合；具体符号/顺序必须用 `example_env.py` 和单任务通道验证。
5. 腿部/灵巧手在挑战赛 `ee` 模式下不直接下发；若 `pivot` 需要下身体，按官方 WLA server 的 `action.pivot` 语义映射。

**关键细节**：WLA 的每个未来动作是“相对 plan-time 当前 EE”的位姿（compose 后才是 base 系绝对目标），不是累积增量；adapter 必须先把整个 30 步 compose 成 base 系绝对目标，再按 5 步切片。否则切片后的第 6-30 步会以错误的锚点解释，产生系统性偏移。

### 4.5 状态机

```text
INIT ──first obs──▶ PLAN ──plan ready──▶ RETRIEVE
  ▲                   ▲                    │
  │                   │                    ├─ confidence high ──▶ SERVO
  │                   │                    │                      │
  │                   │                    │                      ├─ d_t < d_c ──▶ CONTACT
  │                   │                    │                      │                 │
  │                   │                    │                      │                 └─ release ──▶ RETRIEVE
  │                   │                    │                      │
  │                   └── replan ◀── RECOVER ◀── edit_score > θ_e
  │                                      │
  └──────────────────────────────────────┘
任意状态 ──task success / max steps──▶ DONE
```

- `RETRIEVE`：按语言/相位/视觉/行为检索 top-k；置信度低 → `PLAN`（纯 VLA）。
- `SERVO`：PBVS 主导，IBVS 辅助。
- `CONTACT`：法向缩幅、切向保留；`r_grasp` 突变 → 滑移处理。
- `RECOVER`：编辑检测触发；先停，再重定位；目标可见 → 更新 goal；不可见 → VLA 重规划。
- `DONE`：清理状态，等待 `reset()`。

        self.plan = None
        self.plan_idx = 0
        self.history = []
        self.servo.reset()
        self.retrieval = None

    def get_action(self, obs):
        self._tick(obs)
        self._maybe_request_plan(obs)

        phase = self.phase_observer.update(obs)
        contact = self.contact_observer.update(obs)

        if self.need_retrieval(phase, contact):
            q = self.make_query(obs, phase)
            self.retrieval = self.memory.retrieve(q, topk=self.cfg.topk)

        if self.retrieval and self.retrieval.confidence > self.cfg.theta:
            ref = self.align(self.retrieval.best, obs)
            a_ref = ref.actions[: self.H_c]
            if self.cfg.select and contact:
                a_vla = self.vla.sample(obs, k=self.cfg.K)
                a_vla = self.select(a_vla, ref)
            else:
                a_vla = self.plan_slice(self.plan, self.plan_idx, self.H_c)
            a_cmd = self.servo.track(a_vla, a_ref, obs)
        else:
            a_cmd = self.plan_slice(self.plan, self.plan_idx, self.H_c)

        self.plan_idx += self.H_c
        if self.plan_idx >= len(self.plan):
            self.plan = None
            self.plan_idx = 0
        return self.adapter.to_api(a_cmd, obs, self.token)

### 5.4 检索与对齐

```python
def retrieve(self, query, topk=5):
    cand = self.index.filter(task=query.task, phase=query.phase)
    rough = cand.search(query.z, k=50)
    scored = []
    for m in rough:
        s = (self.w_v * cos(query.z, m.z)
             + self.w_l * (query.lang == m.lang)
             + self.w_p * (query.phase == m.phase)
             + self.w_g * exp(-norm(query.g - m.g)**2 / (2*self.sigma**2))
             - self.w_b * dtw(query.history, m.prefix))
        scored.append((s, m))
    scored.sort(reverse=True, key=lambda x: x[0])
    return RetrievalResult(scored[:topk], confidence=calibrate(scored))
```

```python
def align(self, m, obs):
    T_b_e_m = m.T_b_e
    T_b_e_q0 = obs.ee0
    T_start = T_b_e_q0 @ inv(T_b_e_m)
    if m.T_b_o is not None and self.object_pose_valid(obs):
        T_b_o_q = self.estimate_object_pose(obs)
        T_obj = T_b_o_q @ inv(m.T_b_o)
        beta = self.pose_confidence(obs, m)
        T_align = se3_interp(T_start, T_obj, beta)
    else:
        T_align = T_start
    return Trajectory([T_align @ T for T in m.seg])
```

### 5.5 伺服

```python
def track(self, a_ff, a_ref, obs):
    T_e = obs.ee
    T_d = a_ref[0]
    e = log_se3(inv(T_e) @ T_d)
    delta = clip(self.Kp * e + self.Kd * (e - self.e_prev), -self.dp, self.dp)
    self.e_prev = e
    if self.contact:
        delta_n, delta_t = decompose(delta, self.surface_normal)
        delta = self.alpha_n * delta_n + delta_t
    return compose_relative(a_ff, delta)
```

### 5.6 候选选择

```python
def select(self, samples, ref):
    scores = []
    for a in samples:
        s = -min(dtw(a, r) for r in ref.topk)
        s -= self.lambda_s * jerk(a)
        s -= self.lambda_g * abs(close_time(a) - close_time(ref.best))
        scores.append(s)
    if max(scores) - sorted(scores)[-2] < self.margin:
        return medoid(samples)
    return samples[argmax(scores)]
```

## 6. 推导与工程细节

### 6.1 为什么相对位姿能抗位置/干扰

设物体从 `T_b^o(m)` 移到 `T_b^o(q)`，记忆片段中的 EE 轨迹整体左乘 `T_b^o(q)(T_b^o(m))^{-1}`。如果物体只做桌面平移/旋转，这个变换正好把整段轨迹搬到新位置；夹爪与物体的相对关系保持不变。绝对轨迹回放则会把夹爪送到旧位置，误差等于物体位移。

### 6.2 SE(3) 融合

`T_start` 和 `T_obj` 都是刚体变换；用 `log`/`exp` 在切空间线性插值，等价于对螺旋运动插值。`β` 不是学习参数，由物体位姿置信度决定：

```math
\beta = \sigma\left(a\cdot \mathrm{inlier} + b\cdot \mathrm{visibility} - c\cdot \mathrm{reproj} - d\right).
```

离线标定 `a,b,c,d`；不做在线学习。

### 6.3 伺服稳定性

简化离散积分器：

```math
e_{k+1}=e_k-K H_c\,e_{k-d},
```

其中 `d=τ/(H_c/f_c)` 是延迟块数。特征方程：

```math
z^{d+1}-z^{d}+K H_c=0.
```

- `d=0`：`|1-KH_c|<1` → `0<KH_c<2`。
- `d=1`：`z^2-z+KH_c=0`；稳定域 `0<KH_c<1`；增益裕度约减半。
- `d=2`：稳定域进一步缩小；必须降增益或加预测。

实践：

- 用 `τ` 测量值做 Smith 预测：`e_{k+d} ≈ e_k + J_v v τ`。
- 增益调度：`K_eff = K_0 / (1 + τ/τ_0)`；`τ_0` 取 50ms。
- 仿真扫 `τ ∈ {0,50,100,150}ms`；真机只允许在稳定域内。
- 如果 `T_fb > 300ms`，关闭 IBVS，只做 PBVS 粗对齐 + VLA；不要用高增益追。

### 6.4 检索置信度

用三个信号校准：

1. top-1 与 top-k 的分数间隔；
2. top-k 的相对位姿一致性（对齐后轨迹方差）；
3. 几何校验（重投影误差、深度有效像素、物体可见性）。

```math
c = \sigma\left(w_1 \Delta s + w_2 \frac{1}{\mathrm{var}(\tau)} + w_3 \mathrm{inlier} - b\right).
```

`c < θ` → 回退 VLA；`c` 高但动作与 VLA 冲突大 → 降低伺服增益/只做候选选择。

### 6.5 延迟与端口

- 检索/对齐在 CPU；VLA 在 GPU；两者并行。
- `get_action` 永远不阻塞在 VLA 上；用上一版 plan + 伺服。
- 每端口独立状态；共享索引只读；`reset()` 清理 history/plan/servo。
- p99 目标：检索+对齐+伺服 <50ms；VLA 异步；总 `get_action` p99 <150ms。

**任务族**：

1. peg-in-hole（PlugInEthernet/PlugCharger/ArrangeTestTubes）；
2. hang/stack（HangCup/StackBowls/StackCups）；
3. zip/unlock（ZipUp/Unlock/OpenPillBottle）。

**变量**：

- `H_c ∈ {3,5,8,30}`；
- `τ ∈ {0,50,100,150}ms`；
- 检索 on/off；对齐 on/off；伺服 on/off；
- 位置/遮挡/背景/目标移动/人手扰动。

**指标**：成功率、接触误差、收敛时间、超调、恢复率、p99。

**通过标准**：3 个任务族中至少 2 个，检索+对齐+伺服比 VLA-only +10pp；延迟 150ms 不振荡。

### 7.3 Tier 2：单任务真机（1-2 个 slot）

**任务**：PlugInEthernet（插入）、HangCup（挂）、ZipUp（拉链）、StackBowls（叠）、FoldTowel（变形，防回归）。

**设计**：每任务 5 次 A/B（memory off/on）；同一初始条件；记录成功、步骤分、耗时、p99、恢复次数。

**通过标准**：至少 3/5 任务 +10pp；FoldTowel 不回归 >5pp；否则不提交 memory 版本。

**注意**：5 次/任务只能看方向，不能看显著性；汇总 5 任务用 bootstrap 95% CI；CI 跨 0 就继续测或放弃。

### 7.4 全量干跑

- 32×10；N 端口；reset 隔离；内存不涨；p99 ≤150ms；无 NaN/错误 shape。
- 先跑 1 个任务×10 次，再跑 32×1，再跑 32×10。
- 保留回滚开关：memory 关闭、伺服关闭、chunk 30 基线。

## 8. 实验设计与门

### 8.1 离线

| 实验 | 数据 | 指标 | 门 |
|---|---|---|---|
| 检索命中 | 32 任务，按 episode/session 分组 | top-5 含同任务/同相位 ≥80%；对齐后位姿误差 ≤5mm/2° | G1 |
| 相位分割 | 人工标签子集 | 边界 F1 ≥0.75 | G1 |
| 动作回放 | 5 代表任务 | MAE 平移 ≤10mm、旋转 ≤5°；DTW 比 VLA 基线低 ≥15% | G2 |
| 轴扰动 | 5 轴合成 | 检索命中下降 ≤15pp；动作误差上升 ≤20% | G2 |
| 编辑检测 | 合成编辑 + 正常 | AUROC ≥0.85；误报 ≤5% | G4 |

| 实验 | 变量 | 指标 | 门 |
|---|---|---|---|

### 8.5 消融

1. memory on/off。
2. 图像检索 vs 行为检索 vs 混合。
3. 起点对齐 vs 物体对齐 vs 融合。
4. RAP-SELECT on/off；K=1/2/4/8。
5. 伺服 on/off；H_c=3/5/8/30。
6. 相位过滤 on/off。
7. 置信度门控 on/off。
8. WLA Base vs WLA LoRA（在 32 任务上）。

### 8.6 门 G0-G7

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | 数据集能否回放成 API？ | 合规率 100%；5 任务不崩；p99 <150ms | 修 adapter；先不用模型 |
| G1 | 检索是否可信？ | top-5 同任务/同相位 ≥80%；对齐误差 ≤5mm/2° | 改任务级固定相对目标/纯 VLA |
| G2 | 离线/仿真是否涨点？ | 接触相位 DTW -15%；仿真 2/3 任务族 +10pp；150ms 稳定 | 降增益/加 chunk；只做候选选择 |
| G3 | 真机单任务是否涨点？ | 3/5 任务 +10pp；FoldTowel 不回归 | 不提交 memory 版本 |
| G4 | 人为干扰能否恢复？ | 检测 ≤200ms；仿真恢复 ≥70% | 只做离线标注/不线上触发 |
| G5 | 延迟是否可接受？ | p99 ≤150ms；timeout 不升 | 加 chunk/降分辨率/关检索 |
| G6 | 32 任务干跑是否稳定？ | N 端口隔离、reset 干净、内存不涨 | 回退基线 |
| G7 | 消融是否支持因果？ | 物体对齐 > 起点对齐；memory > 无 memory；5 步 > 30 步 | 保留有效部分，砍掉无效部分 |

## 10. 风险与合规

### 10.1 单模型合规的三种模式

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线检索 | 检索只离线生成目标/相位标签；线上只有 VLA | 最低 | 保守首选 |
| C2 同 checkpoint 特征 | 检索用 VLA 同一 checkpoint 的视觉编码器；不加载第二个模型 | 低-中；需说明 | 主推 |
| C3 经典描述子 | ORB/颜色/几何特征；无学习权重 | 低 | 需要强描述子时用 |

禁止：加载第二个学习策略/残差网络/独立视觉编码器做在线决策。检索库是数据，不是模型；伺服是确定性控制器。

### 10.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定为第二个模型 | C1/C2/C3；提交材料写清楚；检索不输出动作 |
| 检索 mismatch | 错误目标/轨迹 | 任务/相位过滤；几何校验；置信度门控；回退 VLA |
| 物体位姿误差 | 对齐偏移 | 多帧/ROI/ICP；置信度融合；回退起点相对 |
| 透明/反光/变形 | 深度/特征失败 | 只对刚体任务启用；腕部 2D + 夹爪滞止兜底 |
| 远程 RTT 高 | 伺服带宽不足 | 5 步 chunk；RTT 测量；预测补偿；回退 chunk 8-10 |
| 腕部外参缺失 | 2D 伺服不准 | WESC 手眼标定；D435 先验；头双目 PBVS 兜底 |
| `pivot` 语义不一致 | 动作被拒/机器人不动 | 先用 `example_env.py`/单任务通道验证；保留零 pivot 回退 |
| gripper 范围不一致 | 夹爪不闭合/过载 | 数据统计 + 单任务通道扫范围；限幅 |
| 头双目是否 rectified | 深度误差 | 用单任务通道校验；必要时在线去畸变 |
| 标定漂移/换机器人 | 残差变大 | 每机器人一次重投影校准；误差大关伺服 |
| 人为干扰不在视野 | 漏检 | 本体/夹爪/任务状态兜底；不声称 100% |
| 安全 | 回撤/重抓碰撞 | 限速/限幅/最大重试；编辑检测即停 |
| 评测噪声 | +1-2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |
| 数据泄漏 | 离线指标虚高 | 按 episode/session/物体/背景分组；相邻帧不跨 split |
| 提交次数限制 | 无法多次 A/B | 邮件确认；单任务通道先验证；一次提交则保守 |
