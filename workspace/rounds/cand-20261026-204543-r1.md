# 第 8 轮 · DIAG：量化买算力，诊断花算力，地形只做余量

> 检索/复核日期：2026-10-26（UTC）。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「模型量化」「地形适应」「故障诊断」。我先给结论：**这三个词不是三条独立战线，而是一条链——量化决定每步能花多少算力，诊断决定算力花在哪，地形/工作空间决定身体够不够得着、看不看得见。** 上一轮 PILOT-GPR 的“终局放置是闸门”仍然成立，但“每次放置都做 SVL”太贵、太窄；本轮把它升级为“诊断门控的可靠性预算”。

## 0. 本轮先核实：榜单仍是占位，数据是全量，pivot 可控制躯干

### 0.1 榜单仍是占位，“榜首 <30%”只能当结构先验

我直接抓了 `leaderboard.html` 与 `leaderboard_data.json`（[S2][S3]）：页面仍是「即将发布 / Coming Soon」，JSON 的 `generated_from` 仍是 `gen_leaderboard.py`，8 个模型 × 32 任务的 256 条 `task_metrics` 是脚本生成的占位数据。占位榜首 **MolmoAct2 29.7% / 39.0 分**，8 模型平均 **25.6% / 34.3 分**；success−step gap 平均 **8.6pp**。

逐任务平均最难：**Plug In Ethernet 17.7%、Unlock 20.1%、Spell robot 21.8%、Organize Stationery 22.5%、Open Pill Bottle 22.7%**；最容易：**Stack Cups 30.3%、Conveyor Food Sorting 29.1%、Paper Cup Stacking 28.0%**。这些数字**不能**用来判断谁强谁弱；它们只能说明“30% 量级”与公开 VLA 在真机 OOD 上的表现一致。用户说的“榜首也不到 30%”与占位榜首 29.7% 对齐，但真实榜单发布后必须重跑这个假设。

### 0.2 数据全量，但“地形”在数据里几乎是常数

数据集已全量：32 任务、**33,276 条、169h、811GB**；StackBowls 单任务 **979 条 / 295,609 帧**，四路相机 480×640/30fps，EE base/torso、waist、lower_body、pivot 等字段齐全（[S8]–[S11]）。官方 HF README 明确：

```text
pivot = [vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]
```

首帧样本与 `state_torso` 的 roll/pitch/yaw + height 对齐（`pivot_3/4/5` 官方语义未写明，标“待核实”）。我抽了 StackBowls / ArrangePlates / StoreCups / OrganizeBookshelf 各 400–2,000 帧：**`action.pivot` 7 维完全常数 `[0,0,0,0,0.15,0,0.74]`，`base_command` 常数，`waist_action_joint` 的 range 只有约 0.1 rad**。这说明演示是固定桌面/固定基座，躯干只做微小调整。

**结论：地形适应在本赛的官方数据/五轴里几乎没有被激励。** 把它当主战线会与评测分布不匹配；保留为 reset 时桌面平面标定、reach/view margin 特征、支撑面分类（布料/传送带/架子），不建地形图、不做 base 行走、不做地形 RL。

### 0.3 接口允许量化与诊断，但延迟会被记录

提交是自部署 + **N 个连续端口（8765…）**，6B WLA 单模型；README 明确会记录 **per-step latency、variability、action regularity**，并可能随成绩公布（[S12]）。观测可裁剪/缩放/堆叠；动作 chunk 自定；动作空间 joint 或 ee；`action.pivot` 必填（7 维 lower-body/pivot target）。这意味着：量化不是“偷偷加速”，而是要在延迟/动作平滑约束下做；诊断/恢复的额外算力必须有预算。

### 0.4 头部方案：三类，五个共同瓶颈

占位榜的 8 个名字对应三类公开方案（排名本身不可信，只借名字做方案解剖）：

- **动作推理 VLA**：MolmoAct2、π0.5、GR00T N1.5、WALL-OSS-0.5；
- **世界模型/WAM**：DreamZero、GigaBrain-0；
- **混合/未明**：Spirit-v1.5、DM0（不推断其真实能力）。

共同瓶颈：

| # | 瓶颈 | 证据 |
|---|---|---|
| B1 | 开环 chunk 与动态干扰 | MolmoAct2 明确“一次规划 10–30 步、批内不重规划”（[S37]）；UniBot 的人为干扰/传送带正好打这个 |
| B2 | 没有显式故障诊断/恢复 | 训练数据全是成功演示；失败时继续执行（[S25]–[S31]） |
| B3 | 算力/延迟/显存 | 6B–14B，N 端口；DreamZero 14B 7Hz；GR00T N1 16 动作 63.9ms/L40（[S41][S45]） |
| B4 | 工作空间/身体 | 固定基座/桌面；G1 腰/髋 DOF 用得少（[S19] 数据统计） |
| B5 | 32 任务长尾与步骤分 | 任务干扰、数据不均、没有步骤级监督（[S6][S7]） |

**结论：再训一个更大的 foundation model 不是我们的相对优势；我们的相对优势是模型无关的可靠性层。**

### 0.5 量化证据：动作感知/混合精度可行，naive 量化会伤动作

- **QVLA**：通道级 bit 分配，OpenVLA-OFT **29.2% VRAM、98.9% 性能、1.49×**；uniform INT8 反而掉点（[S20]）。
- **ActQuant**：3-bit 保留 **95.0%** OpenVLA-OFT、**94.8%** π0.5；2.5bpw 90.1%（[S21]）。
- **FoldQuantVLA**：W4A4 **1.2–1.5×**；保留 attention output/FFN down 为 INT8，真机 GR00T N1.7 **80.0%→92.5%**（[S22]）。
- **ActTune**：动作感知精度分配 + GPU 工作点，**2.02×**、energy/success **−76.8%**（[S23]）。
- **GR00T INT8 edge**：PTQ+QAT 全流程，Bridge 平均 **61.07% vs 61.07%**（[S24]）。

结论：量化可行，但要**动作感知、混合精度、QAT/校准**；不能 uniform W4A4。

### 0.6 诊断证据：这是 30% 的真瓶颈

- **VLA-FixBench**：理想反馈回路 **+13% LIBERO、+35% 真机**（[S25]）。
- **ProbeAct**：training-free 失败检测/恢复，OpenVLA-OFT **69.6%→74.1%**（[S26]）。
- **ActProbe**：纯动作空间 TCE+ACM，F1-timeliness **+12.7%**，早期检测 AUC **+9.0%**（[S27]）。
- **RoboFailRing**：失败记忆检索，OOD 失败检测 **80%**，检测时间减半，VLM 推理 **+35%**（[S29]）。
- **FLARE / VLA-Corrector / FAIL-Detect**：Retry/Reset、阶段感知 verifier、成功数据 + conformal 阈值（[S28][S30][S31]）。

结论：诊断/恢复有 **3–8pp** 的现实空间；关键是**阶段感知、多信号、可校准、恢复原语**。

### 0.7 三个词合起来：可靠性预算

量化省下的算力 Δ 不是用来“更快地重复同样的错误”，而是用来买诊断/恢复：

```text
每步预算 B
全精度成本 c_FP；量化成本 c_Q = c_FP / ρ（ρ=1.3–2.0）
Δ = c_FP − c_Q
Δ 分配给：canary（每 k 步） + 腕部校验 + 诊断 + 恢复/重试
约束：p99 latency ≤ B，动作平滑，恢复次数有上限
目标：max E[success] s.t. latency & smoothness
```

诊断的风险 `r_t` 决定三档：

| 档位 | 条件 | 策略 |
|---|---|---|
| 绿 | `r_t < θ1` | 量化 VLM + FP16 动作头，长 chunk（16–30） |
| 黄 | `θ1 ≤ r_t < θ2` | 动作头切 FP16，短 chunk（4–8），加腕部校验 |
| 红 | `r_t ≥ θ2` | 暂停，诊断失败类型，调用恢复原语，回滚 SSG 步骤 |

地形/工作空间只作为 `r_t` 的特征（reach/view margin）和 reset 标定，不单独开战线。

**这就是本轮的主判断：从“放置优先”升级为“诊断门控的可靠性预算”。**

## 1. 为什么这比上一轮更该做

上一轮说“终局放置是闸门、约 60% 步骤分、跨五轴杠杆”，这是**评分结构**层面的正确判断；但“失败都发生在最后一步”只是弱先验，占位数据不能证明。本轮不再假设失败位置，而是用诊断层**测量每步失败分布**；把 SVL 从 always-on 改为 gated；把预算从“补最弱轴”改为“买可靠性”。

| 关系 | 内容 |
|---|---|
| 保留 | SSG 步骤图、PGL 放置目标阶梯、OPT 少样本位姿迁移、ICR 检索、NRB 官方备注恢复、GPR-VLA/WLA 底座 |
| 升级 | SVL → **诊断门控的 verify/recover**；NRB → **human 干扰诊断剧本**；TCLB → 离线比较 |
| 新增 | **Q-Mix** 动作感知混合精度、**Q-Canary** 双精度差异、**FDRB** 阶段感知故障诊断总线、**Scheduler** 三档算力调度、**Recovery** 诊断条件化原语、**WMA** 工作空间余量 |
| 修剪 | 全地形/地形 RL、base 行走、L2L 降为低优先、FLEET 只做检查单、per-task LoRA、世界模型训练、自由仿真数据、运行时 MPC、布料/拉链/透明全物理 |

## 2. 方案轮廓：DIAG-GPR

```text
语言(160 复述之一) → SSG 评分步骤图 → 当前步骤 s_t
                              │
              ┌───────────────▼────────────────┐
              │ FDRB 阶段感知故障诊断总线        │
              │  TCE/ACM + Q-Canary + proprio   │
              │  + 视觉谓词 + reach/view margin │
              │  → 风险 r_t + 失败类型 d_t      │
              └───────────────┬────────────────┘
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
   绿：量化+长 chunk     黄：FP16+短 chunk      红：暂停+恢复
   Q-Mix VLM W8A8       动作头 FP16            Recovery 原语
   DiT FP16            腕部校验                SSG 回滚/重试
        │                     │                     │
        └─────────────────────┴─────────────────────┘
                              ▼
                 GPR-VLA（单一 checkpoint）
                 语言→z*；4 视图+部件→b；r=z*−b→chunk
                              ▼
                 PGL/OPT 放置目标；SVL gated verify
                              ▼
                 WMA：reset 桌面平面 + reach margin
```

一句话：**用动作感知混合精度买算力，用阶段感知诊断决定花在哪，用诊断条件化恢复把“部分完成但失败”的 episode 捞回来；地形只做工作空间余量。**

## 3. 可证伪的实验与 Go/No-Go

| 实验 | 指标 | Go | No-Go |
|---|---|---|---|
| E1 Q-Mix | 成功率、p99、显存 | 掉点 ≤1pp，≥1.3×，≤60% 显存 | 掉点 >1pp → 回退 FP16 |
| E2 Q-Canary | OOD/失败 AUROC、F1 | AUROC ≥0.7，F1 ≥0.6，FA ≤10% | <0.6 → 砍掉 canary |
| E3 FDRB | 诊断准确率、检测延迟 | ≥60%，≤0.5s | 只用规则/阈值 |
| E4 Scheduler | 成功率 vs p99 | +3pp 或 −30% latency | 固定精度/chunk |
| E5 Recovery | 成功率、恢复成功率 | +3pp，恢复 ≥50% | 只保留回滚 |
| E6 WMA | reach-limited 任务 | +2pp | 砍掉，只留 margin 特征 |
| E7 全系统 | 成功率、步骤分 | +3–5pp / +5–8pp | 提交 E0/E1+SSG 安全版 |

统计：320 计分 trials、p≈0.3、SE≈2.56pp；+3pp 约 80% 概率排名更高，+5pp 约 90%。所有阈值用配对种子 + bootstrap。

## 4. 本轮修剪

| 项 | 决定 | 理由 |
|---|---|---|
| 全地形图/地形 RL/base 行走 | 砍 | 官方五轴不含桌面高度；数据里 pivot/waist 几乎常数 |
| L2L 实验室数据 | 降为低优先 | 外部数据合规未确认；先做协议与法务，不并入训练 |
| FLEET 第六轴 | 降为检查单 | N 端口/延迟/状态隔离是工程前提，不是研究贡献 |
| per-task LoRA | 砍 | 单模型 + 32 任务长尾；用统一 checkpoint + 诊断层 |
| 世界模型训练 | 砍 | 成本高、与“可靠性层”主线无关；可复用公开 WAM |
| 自由仿真数据 | 砍 | 只保留诊断标签用的少量孪生/回放 |
| SVL always-on | 升级为 gated | 每次放置都 verify 太贵；只在黄/红档触发 |
| 外部 VLM 在线诊断 | 砍 | 单模型合规风险；只离线做标注 |

## 5. 一句话押注

**把 30% 当成执行可靠性问题：用动作感知混合精度省出的算力，养一个阶段感知的故障诊断器，只在风险高的时刻花全精度算力和恢复原语；量化是预算，诊断是调度，地形只做工作空间余量。**

## 0. 产物摘要

### 0.1 一句话

### 0.2 组件与是否进推理

| 组件 | 作用 | 进推理？ |
|---|---|---|
| **Q-Mix** 动作感知混合精度 | VLM 主干 W8A8/FP8，DiT 动作头 FP16；按动作通道/层敏感度分配位宽 | 是（部署） |

### 1.3 接口与部署约束

`unibot_submission` README（[S12]；v2 最近提交 2026-08-21 [S13]）给出：

## 2. 定量分析

### 2.1 榜单结构：gap 是上界，不是失败位置

```text
成功率 S = P(所有步骤完成)
步骤分 P = Σ w_i · P(步骤 i 完成)
gap G = P − S  （占位平均 8.6pp）
```

`G` 是“部分完成但失败”的平均部分分上界；它**不告诉**失败发生在哪一步。真实诊断要看**每任务每步的完成率表**（§5.6），这只能从调试槽/计分跑获得。上一轮把 `G` 当成“失败集中在后段”的证据，是不严谨的；本轮修正为“上界 + 待测量”。

### 2.2 可靠性预算：显存/延迟

6B 模型，权重近似：

| 精度 | 权重 | 3 端口权重 | 加激活/KV 估算 | 适配 GPU |
|---|---:|---:|---:|---|
| FP16 | 12GB | 36GB | 42–48GB | 80GB 可行；48GB 紧张；24GB 不行 |
| W8A8 | 6GB | 18GB | 24–30GB | 48GB 可行；32GB 紧张；24GB 边缘 |
| W4A8 | 3GB | 9GB | 15–21GB | 24GB 可行 |

（N 未公开；上表以 N=3 为例。实际以官方 N 为准。）

延迟侧：GR00T N1 16 动作 63.9ms/L40（[S45]）；DreamZero 14B 7Hz（[S42]）；WLA 6B 在单卡上的实际 p99 需实测。目标：**p99 ≤100ms**，chunk 8–16；高风险时缩短 chunk，低风险时放长。

### 2.3 诊断增益上界

若真实榜单的 `G` 也在 8–10pp，诊断+恢复挽回比例 α：

```text
ΔS ≈ α · G
α=0.3 → +2.4–3.0pp
α=0.5 → +4.0–5.0pp
α=0.7 → +5.6–7.0pp
```

保守目标 +3pp，乐观 +5pp。320 trials、p=0.3、SE=2.56pp：+3pp 约 80% power，+5pp 约 90%。这是“值得做”的统计门槛。

### 2.4 工作空间余量

实测 waist range ≈0.1 rad，pivot 常数 → 官方演示的躯干几乎不动。因此：

- **不要**用 WMA 大范围改 pivot/waist；会 OOD。
- **可以**用 WMA 做 reset 桌面平面估计 + reach/view margin 特征；margin 低时触发“换手/换视角/诊断”，而不是直接改姿态。
- 若调试槽显示高架子/低桌面任务（T08/T21/T25）失败与 margin 相关（r>0.2），再考虑小幅 pivot 调整；否则砍掉。

### 2.5 预算分配（修订第 7 轮）

```text
Q-Mix + 部署/延迟           20%
FDRB + Recovery + 诊断数据   35%
SSG/PGL/OPT/SVL（gated）     20%
数据/标定/失败合成           15%
工程/调试回路/合规           10%
```

第 7 轮把 40% 给放置专项；本轮把其中一部分转到诊断/恢复，因为“放置失败”只是失败的一种，诊断层覆盖全部失败类型。

### 3.2 Q-Mix：动作感知混合精度

**目标**：把 VLM 主干压到 W8A8/FP8，把 DiT 动作头留在 FP16；按动作通道/层敏感度分配位宽。

**动作空间敏感度**（本赛接口）：

| 动作组 | 维度 | 敏感度假设 | 建议精度 |
|---|---|---:|---|
| 双臂关节/EE 平移 | 7+7 / 6+6 | 高（放置/插入） | FP16 |
| 腕部旋转 | 3+3 | 高（姿态/插入） | FP16 |
| 夹爪 | 1+1 | 低（开/合） | INT8 可 |
| pivot height/torso | 7 | 低（近常数） | INT8 可 |
| VLM 视觉/语言主干 | 6B | 中（语义/grounding） | W8A8/FP8 |
| VLM 个别层 | — | 高（attention out/FFN down） | 保留 INT8（FoldQuant 式） |

**流程**：

1. 在 1–2k 条分层校准集上，逐层/逐通道测量“量化后动作 chunk 与 FP16 的余弦/最大误差”。
2. 用 QVLA/ActQuant 式敏感度分配：动作误差大的层/通道保留 8-bit，其余 W4/W8。
3. 对 DiT 动作头做 QAT（fake quant + 动作损失 + FP/Q 一致性损失）；VLM 冻结或 LoRA。
4. 导出 TensorRT/ONNX；测 p99、显存、动作平滑；不达标则回退。
5. 模型卡写明：VLM W8A8、DiT FP16、校准集、掉点。

**伪代码**：

```python
def qmix_calibrate(model, calib_loader):
    for batch in calib_loader:
        feat_fp = model.vlm(batch.obs)          # FP16
        a_fp = model.dit(feat_fp, batch.state)  # FP16
        for layer in model.vlm.layers:
            a_q = model.dit(quantize(feat_fp, layer), batch.state)
            err[layer] = action_error(a_q, a_fp)
    bits = allocate_bits(err, budget=8)         # per-layer/channel
    return bits
```

### 3.3 Q-Canary：双精度动作头差异

**假设**：同一 DiT 动作头在 FP16 与 INT8/FP8 下的输出差异 `d_t`，在 OOD/失败前会升高；它可作为“免费”的不确定性信号（不需要 ensemble、不需要第二个模型）。

```text
d_t = || a_FP(t) − a_Q(t) || / (|| a_FP(t) || + ε)
```

- 只在**阶段边界**（抓取前/放置前/插入前）或每 k=5 步算一次；DiT 小，成本可控。
- 校准：在成功演示上取 95/99 分位；在扰动/OOD 数据上测 AUROC。
- 组合：`[d_t, TCE_t, ACM_t, tracking_error, predicate_conf, reach_margin]` → FDRB。
- 若 AUROC <0.6，砍掉；若 0.6–0.7，只作为辅助特征；≥0.7 进主路径。

**注意**：量化误差与 OOD 不是天然等价；ViT 的 OOD 研究（[S50]）和 CompD（[S49]）说明“压缩模型与原模型的输出偏差”可以作为差异信号，但必须校准。不能把 `d_t` 当成万能失败检测器。

### 3.4 FDRB：阶段感知故障诊断总线

**失败分类**（与 32 任务/5 轴对齐）：

| 类型 | 名称 | 典型信号 | 适用任务 | 恢复原语 |
|---|---|---|---|---|
| D1 | 感知/grounding 错 | 选错物体/槽位；锚点漂移；谓词置信低 | T04/T06/T22/T24 | R1 重观测/重定位 |
| D2 | 抓取失败 | 夹爪闭合但无接触；物体滑；抓偏 | 多数抓取任务 | R2 重抓 |
| D3 | 运输碰撞/掉落 | EE 速度异常；物体位姿突变；碰撞近 | T03/T18/T20/T27 | R3 推正/重抓 |
| D4 | 放置/插入失败 | 位姿误差大；插入深度不足；早放/弹跳 | T07/T10/T13/T26/T27 | R4 重放/伺服 |
| D5 | 关节/闭合失败 | 拉链卡；盖子错位；瓶盖咬死 | T12/T14/T17/T19/T23/T31 | R5 重开/重对齐 |
| D6 | 布料/流体 | 折叠漂移；袋子塌；液体洒 | T16/T18/T23/T32 | R6 重铺/重折 |
| D7 | 外部/人干扰 | 手进入；物体被移动；步骤被撤销 | human 轴全部 | R7 等待/重获 |
| D8 | 硬件/跟踪 | 关节限位；跟踪误差；相机遮挡；延迟尖峰 | 全部 | R8 复位/安全停 |
| D9 | 任务进度/规划 | 跳步；顺序错；假完成 | 全部 | R9 回滚步骤 |

**信号**：

| 信号 | 来源 | 计算 | 用途 |
|---|---|---|---|
| TCE | 连续 chunk 重叠段 MSE | `||a_{t-s} − a_t||²` | 计划不稳定/犹豫 |
| ACM | 当前 chunk L2 | `||a_t||` | 过大修正/失控 |
| Q-Canary | FP16 vs INT8 DiT | 归一化 L2 | OOD/数值不稳定 |
| tracking error | 命令 vs 实际关节/EE | `||q_cmd − q_actual||` | 执行失败/限位 |
| gripper contact | 夹爪位置/命令 + 腕部视觉 | 闭合但无物体 | 抓空/滑 |
| visual predicate | SSG 谓词头/关键点 | 物体-容器相对位姿 | 步骤完成/假完成 |
| reach/view margin | 桌面平面 + 目标位置 | 肩距/遮挡/高度 | 工作空间风险 |
| human disturbance | 手检测/物体位移/备注剧本 | 外部变化 | 区分 D7 与自失败 |

**诊断输出**：`r_t ∈ [0,1]`（未来 1–2s 失败风险）+ `d_t`（类型）+ `onset`（起始帧）。

**规则 + 小头**：

- 规则层：阈值用成功演示的 conformal 分位（FAIL-Detect 式），控制误报 ≤10%。
- 小头：1–5M 参数的 LSTM/MLP，输入 1–2s 信号窗；训练标签来自 FailureSynth + 调试槽真实失败；作为 checkpoint 的辅助头（单模型合规）。
- 若小头数据不足，只用规则；不要为了“学一个诊断器”而拖慢主路径。

### 3.5 Scheduler：三档算力调度

```python
def act(obs, s_t):
    feat = vlm_q(obs)                      # W8A8
    r, d = fdrb(feat, obs, s_t)            # risk, failure type
    if r < TH1:
        a = dit_fp16(feat, obs, chunk=24)  # green
        canary_every = 5
    elif r < TH2:
        a = dit_fp16(feat, obs, chunk=6)   # yellow
        a = wrist_verify(a, obs)
        canary_every = 1
    else:
        pause_and_recover(d, s_t)          # red
        a = dit_fp16(feat, obs, chunk=4)
    return a
```

- `TH1/TH2` 由 conformal/网格搜索定；目标：黄档覆盖率 20–40%，红档 <5%。
- 红档恢复有预算：每 episode ≤2 次；长程任务 ≤1 次；总时长守卫。
- 恢复后必须重新进入 SSG 的当前步骤；不能“恢复完继续旧 chunk”。

### 3.6 Recovery：诊断条件化恢复原语

| 原语 | 动作 | 适用 | 成本 | 风险 |
|---|---|---|---|---|
| R1 重观测/重定位 | 腕部抬高/换视角，重检物体/槽位 | D1 | 低 | 视角变化导致新 OOD |
| R2 重抓 | 开爪→后退→重接近→闭合 | D2 | 中 | 物体被推走 |
| R3 推正 | 用指/爪轻推物体到可达/可见位 | D2/D3 | 中 | 推过头/碰撞 |
| R4 重放/伺服 | 抬升→重对齐→慢放→稳定校验 | D4 | 中 | 耗时 |
| R5 重开/重对齐 | 拉开拉链/开盖/回拧→重做 | D5 | 中 | 损坏物体 |
| R6 重铺/重折 | 拉平布料/重整袋口 | D6 | 高 | 长程漂移 |
| R7 等待/重获 | 暂停，跟踪人手/物体，等稳定 | D7 | 低 | 超时 |
| R8 复位/安全停 | 回安全姿态/清限位/报告 | D8 | 低 | 任务失败 |
| R9 回滚步骤 | SSG 回退到上一步/当前步重做 | D9 | 中 | 循环 |

**恢复选择**：`d_t` → 原语表；若两个原语都可行，选成本低/风险低；恢复后重新诊断，连续失败 2 次则放弃该步（保步骤分）。

### 3.7 WMA：工作空间余量（低优先）

```python
def reset_workspace(obs):
    # 头双目的点云 + RANSAC 桌面平面；估计桌面高度/倾角
    plane = fit_plane(stereo_pointcloud(obs))
    # 目标 reach/view margin：肩距、高度、遮挡
    margin = compute_margin(plane, obs.targets, obs.proprio)
    return plane, margin
```

- 只在 reset 做一次；执行中把 `margin` 喂给 FDRB。
- 若 margin 低于演示 5 分位：触发“换手/换视角/诊断”，不直接大改 pivot。
- 支撑面分类：刚性/布料/传送带/架子 → 设置释放高度/速度/settle 窗口；按任务 ID 查表即可，不训练大模型。
- **停止条件**：若离线 margin 与成功率相关性 r<0.2，或调试槽增益 <2pp，砍掉，只保留 margin 特征。

### 3.8 与 SSG/PGL/OPT/ICR/SVL/NRB 的接口

| 组件 | 本轮角色 | 与 FDRB 的接口 |
|---|---|---|
| SSG | 阶段标签/谓词/步骤权重 | 提供 `s_t`、期望时长、谓词置信；诊断按阶段设阈值 |
| PGL | 槽位→锚点→6D | 诊断 D1/D4 时重渲染锚点；高风险时加腕部锚点 |
| OPT | K 条演示的容器系释放位姿 | 诊断 D4 时用中位数/离散度修正目标 |
| ICR | 关系/运动检索 | 诊断 D1/D3 时检索相似成功段作参考；延迟允许才开 |
| SVL | 落点闭环 | 升级为 gated：绿档不做完整 SVL，黄/红档做 |
| NRB | human 剧本 | 训练/评测 D7；诊断到 D7 时用“等待/重获”而非盲重试 |
| GPR-VLA | 唯一学习主干 | 接收 Q-Mix 特征、PGL/OPT 目标、ICR 上下文；输出 chunk |

### 3.9 单模型与合规

- **唯一学习主干**：WLA-1.0-Base 6B（LoRA/动作头微调）。
- **辅助头**：FDRB 小头（1–5M）作为同一 checkpoint 的 auxiliary head；若规则足够，则不训练。
- **确定性代码**：SSG、PGL、OPT 统计、Q-Mix 校准表、Scheduler、Recovery 脚本、WMA 几何。
- **数据**：ICR 库、NRB 剧本、失败记忆是数据，不是模型。
- **量化**：同一权重不同精度，不是第二个模型；模型卡写明。
- **外部 VLM**：只离线标注，不进推理；避免“第二模型”争议。
- **披露**：模型卡列出所有学习组件、数据来源、量化方案、恢复原语；准备“合规编译器”一键导出。

## 4. 训练与标定

### 4.1 数据

| 数据 | 用途 | 规模 |
|---|---|---|
| 官方 33k 成功演示 | 主训练、Q-Mix 校准、canary 校准、诊断负样本 | 32 任务，分层抽样 5–10k episodes |
| FailureSynth | 诊断/恢复标签 | 动作扰动/早放/错抓/物体移动/人干扰，每任务 100–300 条 |
| 官方 human 备注 | D7 剧本/恢复评测 | 32 任务 × 2 条（human_1/human_4） |
| 调试槽真实失败 | 诊断头微调/阈值校准 | 每次 1 任务，累计 100–300 条 |
| 孪生/回放 | 失败合成/验证 | 仅 8 个放置关键任务，不做全 32 |

### 4.2 Q-Mix 校准/QAT

1. 分层校准集 1–2k episodes；与推理同预处理（image_resize、obs_delta）。
2. 逐层/逐通道动作敏感度；分配 W8/W4；DiT 保持 FP16。
3. DiT QAT：fake quant + 动作损失 + FP/Q 一致性；VLM 冻结/LoRA。
4. 导出 TensorRT/ONNX；测 p99/显存/动作平滑。
5. Go/No-Go：掉点 ≤1pp、≥1.3×、≤60% 显存；否则回退。

### 4.3 Q-Canary 校准

1. 在成功演示上算 `d_t` 分布；取 95/99 分位。
2. 构造 OOD：背景替换/未见物体/物体位移/人手进入/动作扰动；算 AUROC/F1。
3. 与 TCE/ACM/ensemble 对比；若增量 <0.03 AUROC，砍掉。
4. 只在阶段边界/每 5 步算，控制延迟。

### 4.4 FDRB

1. 规则层：成功演示的 TCE/ACM/tracking/predicate 分位；conformal 阈值（误报 ≤10%）。
2. 小头：1–2s 窗，输入信号向量；标签来自 FailureSynth + 调试槽；类别平衡；F1/检测延迟。
3. 阶段先验：不同 `s_t` 用不同阈值/先验（抓取 vs 放置 vs 闭合）。
4. 输出校准：温度 scaling/isotonic；风险 `r_t` 要可解释。

### 4.5 Scheduler

- 先网格搜索 `TH1/TH2`；再用离线 bandit/RL 微调（可选）。
- 目标：黄档 20–40%，红档 <5%；+3pp 或 −30% latency。
- 约束：p99 ≤100ms；动作 jerk 不超过基线 1.2×；恢复 ≤2 次/episode。

### 4.6 Recovery

- 脚本原语优先（安全、可解释）；VLA 恢复 prompt 只在高置信诊断时用。
- 训练：在 FailureSynth/调试槽上评测每个原语的恢复成功率/成本；建“诊断→原语”查表。
- 恢复后必须重新进入 SSG 步骤；连续失败 2 次放弃该步。

### 4.7 WMA

- reset 桌面平面（RANSAC）；reach/view margin 计算；支撑面查表。
- 只做特征/标定；不改大范围姿态。
- Go/No-Go：margin 与成功率 r≥0.2；调试槽 +2pp；否则砍。

### 4.8 课程与超参

| 阶段 | 数据 | 目标 | 退出 |
|---|---|---|---|
| 0 | 官方 33k | 复现 WLA 基线 | held-out 不降 |
| 1 | +SSG 标签 | 谓词/步骤稳 | 谓词 F1 +5 |
| 2 | +Q-Mix 校准 | 掉点 ≤1pp | p99/显存达标 |
| 3 | +Q-Canary/FDRB 规则 | 检测 AUROC/F1 | AUROC ≥0.7 |
| 4 | +FailureSynth/小头 | 诊断准确率 ≥60% | 检测延迟 ≤0.5s |
| 5 | +Scheduler/Recovery | +3pp | 调试槽验证 |
| 6 | +WMA（可选） | reach 任务 +2pp | 否则砍 |
| 7 | 全量 + 蒸馏/量化 | 部署稳定 | p99/审计 |

超参沿用第 7 轮：WLA-1.0-Base 6B；LoRA rank 64/alpha 128；DiT 全量或 LoRA；AdamW，lr 1e-4（LoRA）/2e-5（全量），cosine，warmup 3%；global batch 64–128；bf16；chunk 8–30；早停看真实 held-out + 轴诊断。

## 6. 创新点清单（持续迭代）

> 状态：押注=本轮主线；保留=沿用；升级=旧点改造；降级=保留但非主回路；砍=不做。

### I1 Q-Mix 动作感知混合精度（新增，押注）
- **动机**：6B 模型 × N 端口；量化省显存/延迟，但 uniform 量化会伤动作。
- **差异**：按动作通道/层敏感度分配位宽；VLM W8A8/FP8，DiT FP16；QAT + FP/Q 一致性。
- **可行性**：QVLA/ActQuant/FoldQuant/ActTune 证据；WLA 的 DiT 小，24GB 可微调。
- **资源**：1–2k 校准 episodes；8×H100 2–4 天；TensorRT/ONNX。
- **步骤**：敏感度→分配→QAT→导出→p99/显存/掉点。
- **风险**：量化伤精密接触 → 保留 DiT FP16、选择性 INT8、回退。
- **状态**：押注。

### I2 Q-Canary 双精度动作头（新增，押注）
- **动机**：需要免费/低成本的 OOD/失败信号；ensemble 太贵。
- **差异**：同一 DiT 的 FP16 vs INT8 输出差异；不是第二个模型。
- **可行性**：DiT 小；每 5 步/阶段边界算；CompD/量化 OOD 研究支持“差异信号”但需校准。
- **资源**：无额外数据；离线校准 1–2 天。
- **步骤**：校准分布→OOD 扰动→AUROC→阈值→接入 FDRB。
- **风险**：与 OOD 不相关 → AUROC <0.6 砍。
- **状态**：押注（可证伪）。

### I3 FDRB 阶段感知故障诊断总线（新增，押注）
- **动机**：30% 的真瓶颈是执行可靠性；成功演示不教失败。
- **差异**：TCE/ACM + canary + proprio + 视觉谓词 + reach margin；SSG 阶段先验；规则+小头；conformal。
- **可行性**：ActProbe/FAIL-Detect/ProbeAct/VLA-Corrector 证据；小头 1–5M。
- **资源**：FailureSynth 1 周；调试槽真实失败；2–3 天训练。
- **步骤**：信号→规则→小头→校准→诊断矩阵。
- **风险**：误报/漏报 → conformal + 阶段阈值 + 预算守卫。
- **状态**：押注。

### I4 Scheduler 三档算力调度（新增，押注）
- **动机**：固定精度/chunk 浪费算力；高风险时需要更多算力。
- **差异**：绿/黄/红三档；风险门控；与 Q-Mix/Canary 联动。
- **可行性**：ELASTIC/EQRL/RD-VLA 证据；规则版即可先跑。
- **资源**：离线网格/bandit；无新数据。
- **步骤**：阈值→离线评估→调试槽→计分跑。
- **风险**：切换抖动 → 滞后/最小驻留时间；p99 超限 → 降频。
- **状态**：押注。

### I5 Recovery 诊断条件化恢复（升级 SVL/NRB）
- **动机**：盲重试会加重失败；不同失败类型需要不同恢复。
- **差异**：D1–D9 分类 → R1–R9 原语；恢复后回 SSG 步骤；预算受限。
- **可行性**：FLARE/ProbeAct/VLA-Corrector 证据；脚本原语安全。
- **资源**：FailureSynth/调试槽；恢复表。
- **步骤**：原语实现→诊断映射→成功率/成本→预算。
- **风险**：恢复伤物体/超时 → 安全停/次数上限。
- **状态**：押注。

### I6 WMA 工作空间余量（新增，低优先）
- **动机**：高架子/低桌面/遮挡可能造成 reach/view 失败；官方数据几乎不覆盖。
- **差异**：reset 桌面平面 + margin 特征 + 支撑面查表；不建地形图/不做 base 行走。
- **可行性**：双目/RANSAC/几何；数据有 state_torso/state_d435。
- **资源**：轻量；1 人周。
- **步骤**：平面→margin→特征→调试槽。
- **风险**：官方桌面固定 → 无增益；margin 不相关 → 砍。
- **状态**：低优先/可证伪。

### I7 SSG 评分步骤图（保留，升级）
- **动机**：官方步骤/权重公开；成功=全步骤；诊断需要阶段标签。
- **差异**：从“门控”升级为“诊断的阶段先验”；160 条复述匹配。
- **可行性**：确定性代码 + 谓词头。
- **资源**：无额外数据；1 人周。
- **步骤**：解析 info.json→图→谓词→reset 状态机。
- **风险**：谓词噪声 → 演示统计校准；语言未覆盖 → 嵌入兜底。
- **状态**：保留/升级。

### I8 PGL + OPT（保留，gated）
- **动机**：放置是终局闸门/大头；显式锚点/位姿迁移有效。
- **差异**：只在黄/红档或 D1/D4 时启用，降低常态成本。
- **可行性**：AnySlot/SpaceVLA/FlowRetrieval 证据；数据字段齐。
- **资源**：8 个放置任务 H_i 库；2–3 天。
- **步骤**：容器位姿→H_i→检索 K→执行/伺服/退化。
- **风险**：透明/布料失效 → 分桶回退。
- **状态**：保留。

### I9 ICR 检索上下文（保留，降优先）
- **动机**：33k 是现成少样本库；检索可抗 OOD。
- **差异**：关系/运动键 + SSG 相位；训练期注入；延迟预算。
- **可行性**：ICI-VLA/RA-VLA/FlowRetrieval 证据。
- **资源**：编码 1–2 天；HNSW；缓存 <1GB。
- **步骤**：切段→键→缓存→训练注入→延迟压测。
- **风险**：p99 超标 → 降 K/降维/预取；透明任务失效 → 回退。
- **状态**：保留/降优先。

### I10 SVL（升级为 gated）
- **动机**：释放失败靠“放完就完”无法发现。
- **差异**：绿档不做完整 SVL；黄/红档做缓放→稳定→nudge/regrasp。
- **可行性**：腕部相机 + 谓词；180s 预算。
- **资源**：无新数据。
- **步骤**：稳定性检测→修复库→预算→SSG 接线。
- **风险**：耗时/误判 → 双阈值/次数上限。
- **状态**：升级。

### I11 NRB（升级为 human 诊断剧本）
- **动机**：官方 human 备注是逐任务干扰剧本；诊断要区分自失败/人干扰。
- **差异**：从“训练恢复”升级为“D7 诊断+评测剧本”；等待/重获优先。
- **可行性**：备注多为 1-DOF 平移/撤销；合成/回放便宜。
- **资源**：ACP/孪生 2.5D；32×2 剧本。
- **步骤**：备注表→场景→诊断标签→恢复评测。
- **风险**：编号含义未核实 → 同时覆盖通用扰动。
- **状态**：升级。

### I12 GPR-VLA / WLA 底座（保留）
- **动机**：6B、Apache-2.0、24GB 可微调；动作专家/冻结 VLM 结构适合 Q-Mix。
- **差异**：不变，作为唯一学习主干；加辅助诊断头。
- **风险**：底座微调不足 → LoRA 分级；量化掉点 → 回退。
- **状态**：保留。

### I13 L2L 产学研数据（降为低优先）
- **动机**：背景/位置多样性；实验室网络是便宜来源。
- **差异**：逐字段协议 + QA + 许可 + 署名；但外部数据合规未确认。
- **资源**：3 实验室 × 2 任务 × 100–200 条。
- **步骤**：协议→试点→QA→合规开关。
- **风险**：规则禁止 → 转赛后；硬件异构 → 限 G1+Dex1。
- **状态**：降级（默认 OFF）。

### I14 DebugLoop（保留，核心）
- **动机**：比自建孪生更可信；发布门。
- **差异**：制度化使用不计分单任务调试；按失败类型选任务。
- **资源**：预约/管理；少量真机时段。
- **步骤**：任务选择→判定→记录→复盘。
- **风险**：槽稀缺 → 每版本 1 槽。
- **状态**：保留。

### I15 FLEET 工程检查单（降级）
- **保留事实**：N 端口 8765、每端口独立、状态隔离、延迟弹性、健康检查。
- **不再当研究轴**；作为 soak/部署检查单。
- **状态**：降级。

### 已砍清单（跨轮）
