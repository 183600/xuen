# 第 55 轮（承接第 54 轮 v16 GroundEdge-GenSim+++；灵感循环第 6 轮；本轮灵感：「用户体验」×「分层规划」）

> 第 54 轮把技能组合推进到动作-鲁棒性双证书（α_S/A_cert/γ_ce/δ_a），但其全部产出是**机器可验证**的，不是**人可理解、可信任、可操作**的。本轮聚焦两条新裂缝：H22：证书 sound ≠ 用户可据以决策，投影失真会同时制造“过度信任”与“过度干预”；H23：分层规划的层间证书不可直接复合，失败若回传到错误层级，用户只会收到不可行动的告警。核心主张：把“证书”升级为“可信的用户体验界面”，把“云边两平面”扩展为“意图-任务-技能-动作”的分层规划栈。

## 0. 直觉与动机

**灵感 1（证书 → 用户体验投影：从高维向量到三元决策）**
直觉：没有人会去读 `ρ=(0.91,0.87,…)` 与 `δ_a<Θ_a`。用户只问三件事：**能不能做（confidence）、为什么（cause）、我该做什么（actionability）**。因此需要显式的投影算子 `π_u : J → U = (c, R, Q, ℓ)`，其中 `c` 是校准置信度，`R` 是原因集，`Q` 是可行动等级，`ℓ` 是披露层级。关键约束不是“好看”，而是 **no-overclaim（不夸大）**：投影后的置信度不得超过证书给出的可靠性下界，否则 UX 会系统性诱导过度信任。

**灵感 2（分层规划 → 层间细化契约与懒惰下降）**
直觉：具身任务天然是 L0 用户意图 → L1 任务计划 → L2 技能组合 → L3 动作执行。每层持有自己的证书 `J_l`，层间存在**细化关系** `P_{l+1} ⊑_l P_l` 与**细化义务** `Obl_l`。规划不必一次展开到底：只有当高层证书是“条件性”的（`J_l = conditional`）时才下降到下一层验证。这把第 54 轮的“云边一次映射”变为**按需展开的证书栈**，避免在动作层为高层语义错误白白烧算力。

**灵感 3（渐进披露 → 注意力是稀缺带宽）**
直觉：用户注意力 `B_u` 和边端带宽一样是预算。每条报告 `e` 有认知成本 `κ(e)` 与信息价值 `v(e)`。报告策略 `σ` 是在 `Σκ(e) ≤ B_u` 约束下最大化 `Σv(e)` 的背包问题。原则：**在最粗且仍可行动的层级报告**；更细的层内细节只在用户主动下钻时展开。这与分层规划天然同构——层级就是天然的披露粒度。

**灵感 4（责任归因 → 把失败送到“对的那一层”）**
直觉：失败证据在 L3 出现，但根因可能在 L1（任务分解错）或 L2（技能组合错）。若一律冒泡到用户界面，会得到“动作超时”这类**不可行动告警**；若一律在 L3 重试，会陷入“越修越错”。因此需要**反事实责任归因** `a(f) ∈ Δ(L)`：把第 l 层替换为 oracle，看失败率下降多少，下降最多且可行动的最粗层即为路由目标。只有该层既不可自动修复、又属于人类可控范围时，才升级给用户。

**灵感 5（信任校准闭环 → 把“信任”当作可控状态量）**
直觉：UX 的目标不是让用户喜欢系统，而是让用户的**信任与系统真实可靠性对齐**。设信任状态 `τ`、真实可靠性 `r`，校准误差 `|τ-r|`，用 ECE 度量。每次结果反馈和每次披露都更新 `τ`。过度信任的代价是漏检长尾失败，过度干预的代价是效率坍缩；两者都由校准误差统一刻画。这把第 53/54 轮的 Explain 通道从“解释正确性”推进到“解释被正确理解”。

**灵感 6（层次化 UX 的金字塔叠加）**
直觉：在第 54 轮动作协同层 `𝔸` 之上叠加 **用户体验层 `𝕌`**：`𝕌_0` 原始信号，`𝕌_1` 证书投影，`𝕌_2` 分层披露，`𝕌_3` 信任校准。跨层传递的对象从“双证书”升级为 **`(J, U, a, τ)` 四元组**，形成“机器可验证 + 人可行动”的双轨证书体系。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（分层规划栈与细化关系）**
分层规划栈 `𝓗 = (L0, L1, L2, L3)`：`L0` 用户意图（自然语言/目标约束），`L1` 任务计划（符号分解），`L2` 技能组合（第 54 轮 `G_S` 上的路径），`L3` 动作执行（`A_e` 上的轨迹）。细化关系 `P_{l+1} ⊑_l P_l` 表示 `P_{l+1}` 是 `P_l` 的合法实现。每层携带证书 `J_l` 与**细化义务** `Obl_l = (pre_l, post_l, budget_l)`。**懒惰细化**：仅当 `J_l` 为 `conditional` 时生成 `P_{l+1}`。

**定义 122（用户体验投影）**
投影算子 `π_u : J_l × context → U = (c, R, Q, ℓ)`：
- `c ∈ [0,1]` 校准置信度；
- `R ⊆ Causes` 原因集（可读的根因集合）；
- `Q ∈ {auto, one_tap, manual, unsafe}` 可行动等级；
- `ℓ ∈ {L0,…,L3}` 披露层级。
**保真性（no-overclaim）**：`c ≤ ρ_low(J_l)`，其中 `ρ_low` 是证书给出的可靠性下界；且若 `J_l = reject` 则 `c ≤ c_reject`。称 `π_u` 为**保真投影**当且仅当保真性成立且对 `ℓ` 单调（更粗层级不夸大）。

**定义 123（注意力预算与报告策略）**
用户注意力预算 `B_u`。报告事件 `e = (level, U, urgency)` 具有认知成本 `κ(e)`（可用阅读时长/决策负荷代理）与信息价值 `v(e)`（对用户正确决策的互信息增益）。报告策略 `σ: Events → 2^{Events}` 求解：
```
max_σ Σ_{e∈σ} v(e)   s.t.  Σ_{e∈σ} κ(e) ≤ B_u,  ℓ(e) 为可行动最粗层
```

**定义 124（反事实责任归因）**
给定失败证据 `f`，第 `l` 层的责任：
```
a_l(f) = E[ 1_fail | do(P_l = oracle) ] - E[ 1_fail | do(P_l = oracle ∀l) ]
```
即“仅把第 l 层替换为 oracle 时，失败率的下降量”。归一化 `a(f) = a/Σa ∈ Δ(L)`。路由目标 `l* = argmin{ l : a_l ≥ θ_blame 且 Q(l) ≠ auto }`（最小可行动层）。

**定义 125（信任校准）**
用户信任状态 `τ ∈ [0,1]`，系统真实可靠性 `r`。校准误差 `cal(τ,r) = |τ - r|`；分层校准 `ECE = Σ_b (n_b/N)·|τ̄_b - r̄_b|`。更新规则 `τ_{t+1} = (1-η)τ_t + η·(outcome_t ⊕ disclosure_t)`，其中 `⊕` 表示结果与解释共同作用，`η` 为遗忘因子。

**定义 126（层次化用户体验证书）**
分层 UX 证书 `H = (J_0..J_3, ⊑, π_u, a, τ, Obl)`。称 `H` **层次 sound** 当且仅当：
```
(∀l) [ J_l sound ] ∧ [ 细化成功 ⇒ J_{l+1} 继承 J_l 的下界 ] ∧ [ 失败 ⇒ ∃ l*, a_{l*}≥θ_blame, ℓ(l*) 可行动 ] ∧ [ Σκ(σ) ≤ B_u ]
```
即：机器证书逐层 sound、细化不丢失保证、失败可被归因到最小可行动层、且不超注意力预算。

## 2. 关键算法 伪代码

### IP-121 HIP（Hierarchical Intent Planning，懒惰细化）

```python
def hierarchical_plan(intent, stack, budget):
    P = [parse_intent(intent)]          # L0
    for l in range(0, 3):
        J_l = certify_level(P[l], stack[l])
        if J_l.status == 'definitive_ok':
            return P, J_l               # 高层已可判定，不下钻
        if J_l.status == 'reject':
            return ('reject', J_l, l)
        P.append(refine(P[l], stack[l])) # 仅 conditional 才展开
    return P, certify_level(P[3], stack[3])
```

### IP-122 UXP（User eXperience Projection）

```python
def project_ux(J, context):
    c = min(confidence_of(J), reliability_lower_bound(J))   # no-overclaim
    R = humanize_causes(J.evidence)                         # 只保留可命名根因
    Q = actionability_of(J)                                 # auto/one_tap/manual/unsafe
    l = coarsest_actionable_level(J, Q, context.budget_u)   # 渐进披露
    return U(confidence=c, causes=R, actionability=Q, level=l)
```

### IP-123 AAR（Attention-Aware Reporting）

```python
def allocate_reports(events, B_u):
    # 0/1 背包：价值密度降序 + 层级粗优先做平局裁决
    ranked = sorted(events, key=lambda e: (v(e)/κ(e), -e.level), reverse=True)
    chosen, used = [], 0.0
    for e in ranked:
        if used + κ(e) <= B_u:
            chosen.append(e); used += κ(e)
    return chosen
```

### IP-124 RRA（Responsibility Attribution）

```python
def attribute_failure(f, H, levels=range(4)):
    base = fail_rate(f)                      # 当前策略下的失败率
    full = fail_rate(f, oracle_all=True)     # 全部 oracle 后
    a = {}
    for l in levels:
        only_l = fail_rate(f, oracle={l})    # 仅第 l 层 oracle（反事实）
        a[l] = only_l - full
    a = normalize(a)
    for l in levels:                         # 最小可行动层优先
        if a[l] >= THETA_BLAME and actionability(l) != 'auto':
            return l, a
    return None, a                           # 可自动修复，不打扰用户
```

### IP-125 TCL（Trust Calibration Loop）

```python
def update_trust(tau, outcome, disclosure, eta=0.2):
    observed = 1.0 if outcome == 'success' else 0.0
    signal = observed if disclosure is None else combine(observed, disclosure)
    tau_new = (1 - eta) * tau + eta * signal
    return tau_new, abs(tau_new - reliability_estimate(outcome))
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| HIP | O(Σ_l \|P_l\| · \|𝔇\|) | O(Σ_l \|P_l\|) | 细化保序、证书下界继承 |
| UXP | O(\|J\| + \|Causes\|) | O(\|R\|) | no-overclaim、ℓ 单调 |
| AAR | O(\|E\| log \|E\|) | O(\|E\|) | 成本可加、价值次模 |
| RRA | O(4·T_sim) | O(4) | 反事实可识别、归因归一 |
| TCL | O(1) 每步 | O(1) | 遗忘因子稳定、ECE 有界 |

**正确性定理（UX-Aware Hierarchical Soundness）**
承接第 53/54 轮 (A22)–(A28)；新增：
**(A29)** `π_u` 为保真投影（no-overclaim 且 ℓ 单调）；
**(A30)** 责任归因反事实可识别，`a(f)` 估计误差 ≤ ε_a；
**(A31)** 报告策略满足 `Σκ(σ) ≤ B_u`；
**(A32)** 细化关系 ⊑ 保序，且 `J_{l+1}` 继承 `J_l` 的可靠性下界。
则用户做出正确决策的概率满足：
```
P(correct decision) ≥ 1 - Σ_d (1-ρ_min(d)) - β_E - P(δ_a > Θ_a) - P(overclaim) - P(attribution error > ε_a)
```
且分层信任校准误差 `ECE ≤ ε_trust`。核心：**机器 soundness 是必要不充分条件；只有保真投影 + 最小可行动归因 + 预算约束三者同时成立，soundness 才转化为“人可依赖”。**

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| π_u 有损压缩诱导过度信任 | 高 | no-overclaim 硬约束 + 保真性单元测试 + 信任绊线 |
| 反事实归因把相关当因果 | 高 | 结构化仿真 oracle + 随机化干预 + Shapley 复核 |
| 分层证书下界在细化中丢失 | 高 | 细化契约形式化 + 属性测试（property-based） |
| 注意力预算估计偏差 | 中 | 在线标定 κ + 自适应 B_u |
| 过度披露导致告警疲劳 | 中 | 最小可行动层 + 去重 + hysteresis |
| 层间语义断层 | 中 | 共享本体 + 接口契约 + 端到端回放 |

## 6. 本轮最大风险

**一句话**：把证书投影为“可信用户体验”并用分层归因把失败送到最小可行动层，确实把“机器 sound”推进到“人可依赖”，但整条链路的安全阀是 **`π_u` 的保真性 + 反事实归因的因果可识别性 + 层级下界在细化中的不丢失**——三者任一失守，系统都会在离线指标全绿的同时，让用户对长尾失败形成系统性错误信任；因此必须以 **no-overclaim 硬约束 + 反事实归因审计 + 信任校准绊线** 三层护栏，宁可对用户说“不确定、请下钻”，也绝不把“看起来 sound 的界面”当作真实可靠性。

### IP-123 AAR（注意力预算背包）

```python
def allocate_reports(events, B_u):
    ranked = sorted(events, key=lambda e: (v(e)/max(kappa(e),1e-6), -e.level),
                    reverse=True)
    chosen, used = [], 0.0

# e2 L3: v=5, κ=2 -> 2.5
# e3 L2: v=4, κ=6 -> 0.67
# 密度序：e2(2.5) -> e1(2.0) -> e3(0.67)；选中 e2,e1，used=5≤10，
```

### IP-124 RRA（反事实归因）

```python
def attribute_failure(f, H, levels=range(4)):
    full = fail_rate(f, oracle_all=True)
    a = {}
    for l in levels:
        only_l = fail_rate(f, oracle={l})     # do(P_l=oracle)
        a[l] = max(0.0, only_l - full)
    a = normalize(a)
    for l in levels:
        if a[l] >= THETA_BLAME and actionability(l) != 'auto':
            return l, a                        # 最小可行动层
    return None, a                             # 可自动修复，不打扰用户
```

### IP-125 TCL（信任校准）

```python
def update_trust(tau, outcome, disclosure, eta=0.2):
    observed = 1.0 if outcome == 'success' else 0.0
    signal = observed if disclosure is None else combine(observed, disclosure)
    tau_new = (1 - eta) * tau + eta * signal
    return tau_new, abs(tau_new - reliability_estimate(outcome))

def ece(taus, rs, bins=10):
    # 分层校准：按置信度分箱，加权平均 |tau_bar - r_bar|
    total = len(taus)
    return sum(len(b)/total * abs(mean(tau_b)-mean(r_b))
               for b in split_bins(zip(taus, rs), bins))
```

### IP-126 HUX-Cert（层次 sound 校验）

```python
def certify_hierarchy(H, f_evidence, B_u):
    for l in range(4):
        if not sound(H.J[l]):
            return ('reject', 'machine_unsound', l)
        if l > 0 and not inherits_bound(H.J[l], H.J[l-1]):
            return ('reject', 'bound_lost', l)      # A32 违约
    for U in map(lambda J: H.pi_u(J), H.J):
        if not within_lower_bound(U, J):            # no-overclaim
            return ('reject', 'overclaim', U)
    l_star, a = attribute_failure(f_evidence, H)
    reports = allocate_reports(make_events(a, l_star), B_u)
    return ('ok', HUXCert(H.J, l_star, a, reports))
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| HIP | O(Σ_l \|P_l\|·\|𝔇\|) | O(Σ_l \|P_l\|) | 细化保序，下界继承 |
| UXP | O(\|J\|+\|Causes\|) | O(\|R\|) | no-overclaim，ℓ 单调 |
| AAR | O(\|E\| log \|E\|) | O(\|E\|) | 成本可加、价值次模 ⇒ 贪心近似比 ≥ 1-1/e |
| RRA | O(4·T_sim) | O(4) | 反事实可识别，归因归一 |
| TCL | O(1)/步 | O(1) | 遗忘因子稳定，ECE 有界 |
| HUX-Cert | O(\|J\|+\|E\| log\|E\|+4T_sim) | O(\|J\|+\|E\|) | 四条件合取 sound |

**正确性定理（UX-Aware Hierarchical Soundness）**
假设第 53/54 轮 (A22)–(A28) 成立；新增 (A29) `π_u` 保真 (no-overclaim, ℓ 单调)；(A30) 反事实归因可识别且误差 ≤ ε_a；(A31) `Σκ(σ)≤B_u`；(A32) 细化保序且下界继承。则：
```
P(correct user decision) ≥ 1 - Σ_d(1-ρ_min(d)) - β_E - P(δ_a>Θ_a) - P(overclaim) - P(attribution error > ε_a)
ECE ≤ ε_trust
```
**证明思路**：机器 side 由第 54 轮定理给出 `P(success)` 下界；UX side 需要“成功/失败被正确传达”。若 `π_u` 保真，则用户观测到的置信度不超过真实下界（不夸大）；若归因误差 ≤ ε_a，则正确层级被路由的概率 ≥ 1-ε_a；若预算满足，则关键信息不被丢弃。三者取并集界即得结论。**关键洞察：soundness 不会自动传播到人，必须由 π_u、a、σ 三个算子显式搬运。**

## 6. 本轮最大风险

**一句话**：把证书投影为“可信用户体验”并用分层归因把失败送到最小可行动层，确实把“机器 sound”推进到“人可依赖”，但整条链路的安全阀是 **`π_u` 的保真性 + 反事实归因的因果可识别性 + 层级下界在细化中的不丢失**——三者任一失守，系统都会在离线指标全绿的同时，让用户对长尾失败形成系统性错误信任；因此必须以 **no-overclaim 硬约束 + 反事实归因审计 + 信任校准绊线** 三层护栏，宁可对用户说“不确定、请下钻”，也绝不把“看起来 sound 的界面”当作真实可靠性。
