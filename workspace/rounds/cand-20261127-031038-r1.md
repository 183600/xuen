# 第 1 轮想法区 · 推理延迟 × 末端位姿

## 1. 直觉：一张照片与一只正在移动的手

「推理延迟」与「末端位姿」单独看都是工程老问题：前者是实时性指标，后者是运动学状态。但把它们放进同一个控制环，会出现一个被现有证书体系（v23 的 HPC-E+ 四证）**结构性漏掉**的量——**执行时刻的位姿误差**。

设想机械臂末端正在移动，相机在 $t_0$ 拍下一帧，感知、共识、四证准入、云端校验一共花了 $L$ 毫秒，指令在 $t_0+L$ 才真正落到关节。即使：

- 感知很准（$\varepsilon_{\text{perc}}$ 小），
- 运动学标定很准（$\varepsilon_{\text{kin}}$ 小），
- 云端证书全部通过（合规、能耗、专利都没问题），

手仍然在这 $L$ 毫秒里移动了。真正决定是否碰撞的，不是"照片里手在哪"，而是"指令生效那一刻，控制器**以为**的手位姿与手**真实**位姿之间的差"。

所以核心直觉是一句话：**延迟不是单纯的"慢"，它是空间位移的放大器。** 一张合格的延迟证书与一张合格的位姿证书，可以在组合后变成一张不合格的证书。v23 把每个证书都做成"时间点快照"，却没有为"快照之间的时间差会转化为空间误差"立法。

## 2. 从直觉到研究问题

现有 v23 的证书链（SDC / CAC / ACSC / DCSC / CESC / FSVC / HPC-E+）都隐含假设：证书在某个时刻被签发，就在该时刻被消费，时间差可忽略。但真实流水线是**异步**的：

1. 位姿证书可能来自 $t_1$，障碍图来自 $t_2$，能耗来自 $t_3$，它们被"拼"成一份联合证书，而机器人在 $t_1\to t_3$ 之间已经移动。
2. 云端更新（CESC 双轨切换）会引入延迟尖峰，恰好可能发生在截止期边缘。
3. 少样本适应（FSVC）改变了预测器，但没人重新认证"新预测器在长尾延迟下的外推误差"。

于是本轮的研究问题不是"如何降低延迟"（工程优化），而是：

> **如何把延迟作为证书的一等公民，使"时间上的不确定性"可机械地转化为"空间上的误差界"，并保证多张异步证书被融合时不会产生时间错位的假安全？**

## 3. 关键洞察：在延迟的尾部评估位姿

设末端位姿轨迹 $X(t)\in SE(3)$，感知在 $t_0$ 给出 $\hat X(t_0)$，预测器外推 $\tilde X(t_0+\tau)$。在左不变度量 $d(A,B)=\|\log(A^{-1}B)\|_\xi$ 下可分解：

$$
e_{\text{total}}(\tau)=d(\tilde X(t_0+\tau),X(t_0+\tau))
\le \varepsilon_{\text{perc}}+\varepsilon_{\text{motion}}(\tau)+\varepsilon_{\text{kin}} .
$$

若 $\varepsilon_{\text{motion}}(\tau)$ 关于 $\tau$ 单调不减（运动学上很自然：外推越远越不准），则事件 $\{L\le D\}$ 自动蕴含 $\{e_{\text{total}}(L)\le \rho(D)\}$。也就是说：

> **不必在平均延迟处评估位姿，而应在延迟的截止期（尾部）处评估位姿。** 这既更安全（尾部就是最坏情况），又能把两个独立的尾部约束塌缩成一个。

这就是本轮的核心证书：**LPCC（Latency–Pose Coupled Certificate，延迟—位姿耦合证书）**——它要求"截止期达成概率"与"截止期处位姿管道半径"同时满足，并且管道半径必须被几何净空（来自 CAC/ACSC）支配。

## 4. 方案轮廓（对应产物区）

在 v23 基础上新增一层"时间—空间"证书，而不是替换原有四证：

1. **IP-440 LBC（延迟预算证书）**：用在线样本 + 极值/保形方法给出 $P(L\le D)\ge 1-\delta_t$，并识别延迟的慢变/突变两种机制。
2. **IP-441 PPC（位姿传播证书）**：把延迟窗口 $\tau$ 映射为位姿管道半径 $\varepsilon_{\text{perc}}+\varepsilon_{\text{motion}}(\tau)+\varepsilon_{\text{kin}}$，在 SE(3) 上做区间/Lie 代数膨胀。
3. **IP-442 LPCC（耦合证书）**：核心准入门，在 $\tau=D$ 处评估管道，要求 $\rho(D)+\text{safety\_buffer}<\text{clearance}$。
4. **IP-443 TCF（时间一致性融合）**：给每张证书加 TTL 与时间戳，强制融合时最大时间偏斜 $\tau_{\text{skew}}$ 受限，否则拒证——防止"弗兰肯斯坦证书"。
5. **IP-444 PPEC（预测外推证书）**：对学习型预测器的外推残差做保形校准，给出 $\varepsilon_{\text{motion}}(\tau)$ 的有限样本上界。
6. **IP-445 ALPBA（自适应延迟预算分配）**：把总截止期当预算，在"感知精化 / 预测 / 云校验"等可选阶段间做背包式分配，目标是最大化几何净空余量。
7. **IP-446 CFC++++（时间化共识）**：投票票据带时间戳与各自延迟，要求时间对齐窗口内才可仲裁。
8. **IP-447 HPC-E++ / Exec_v24**：把 LPCC 与 TCF 作为新过滤器并入，保持单调链。

## 5. 与 v23 的关系

v24 不推翻 v23，而是在其外层加一个"时空投影"：v23 回答"这张证书在其签发时刻是否成立"，v24 回答"这张证书在被消费的时刻是否仍然成立，且其时间差带来的空间位移是否仍在安全包络内"。形式上：

$$
\mathrm{Exec}_{v24}=\mathrm{Exec}_{v23}\cap \mathrm{Fil}_{\text{lpcc}}\cap \mathrm{Fil}_{\text{tc}}\subseteq \mathrm{Exec}_{v23}.
$$

这样既保留原有全部安全/合规/专利保证，又把"时间"纳入可复核的证书链。

## 6. 需要警惕的假设

本轮方案有一个漂亮的塌缩，但它压在一个很强的假设上：$\varepsilon_{\text{motion}}(\tau)$ 单调不减。若用学习型预测器，残差在长尾延迟处可能**非单调**（例如预测器在 $\tau\approx D$ 处反而靠模式记忆"蒙对"），此时"尾部即最坏"失效，必须在 $[0,D]$ 上取上确界，保守度会回升。这是下一轮必须处理的理论缺口。

**本轮最大风险**：把延迟当作可加的空间误差、并只在截止期处评估，其正确性依赖"外推误差随延迟单调"与"延迟分布平稳"；一旦学习型预测器非单调或云边切换使延迟分布突变，"尾部即最坏"的塌缩会失效，证书将在真实执行时低估位姿误差。

```python
# ============================================================
# IP-440 Latency Budget Certificate (LBC)
# ============================================================
class LatencyBudgetCertificate:
    def __init__(self, D: float, delta_t: float = 1e-3,
                 window: int = 2000, regime_hysteresis: float = 1.5):
        self.D = D
        self.delta_t = delta_t
        self.samples = deque(maxlen=window)     # 在线延迟样本 (ms)
        self.regime = "steady"                   # steady | burst
        self.regime_threshold = regime_hysteresis

    def observe(self, latency_ms: float):
        self.samples.append(latency_ms)
        # 机制切换检测：近期中位数显著抬升 → burst（云边切换/网络抖动）
        if len(self.samples) >= 50:
            recent = sorted(self.samples)[-50:]
            base = sorted(self.samples)[:-50] or recent
            if median(recent) > self.regime_threshold * median(base):
                self.regime = "burst"
            elif median(recent) < 1.1 * median(base):
                self.regime = "steady"

    def deadline_probability(self) -> float:
        """P(L <= D) 的经验/保形下界。"""
        n = len(self.samples)
        if n < 30:
            return 0.0
        on_time = sum(1 for x in self.samples if x <= self.D)
        # Clopper-Pearson 单侧下界（比 Hoeffding 更紧且适配小样本）
        return clopper_pearson_lower(on_time, n, self.delta_t)

    def admits(self) -> bool:
        # burst 机制下更保守：要求更低的违约率
        p = self.deadline_probability()
        return p >= 1.0 - self.delta_t


# ============================================================
# IP-441 Pose Propagation Certificate (PPC)
# ============================================================
@dataclass
class PoseCertificate:
    t0: float
    X_hat: np.ndarray          # SE(3) 估计
    eps_perc: float            # 感知位姿误差半径
    eps_kin: float             # 运动学标定误差半径
    ttl: float = 0.05

class PosePropagationCertificate:
    def __init__(self, se3_metric: 'SE3Metric', predictor: 'PosePredictor'):
        self.metric = se3_metric
        self.predictor = predictor

    def tube(self, pose: PoseCertificate, tau: float) -> tuple[np.ndarray, float]:
        """返回 (外推位姿, 管道半径 rho(tau))。"""
        X_pred = self.predictor.extrapolate(pose.X_hat, tau)
        eps_motion = self.predictor.conformal_radius(tau)   # 见 IP-444
        rho = pose.eps_perc + eps_motion + pose.eps_kin
        return X_pred, rho


# ============================================================
# IP-442 Latency–Pose Coupled Certificate (LPCC) —— 核心
# ============================================================
class LatencyPoseCoupledCertificate:
    def __init__(self, lbc: LatencyBudgetCertificate,
                 ppc: PosePropagationCertificate,
                 delta_s: float = 1e-3, beta_buf: float = 0.005):
        self.lbc = lbc
        self.ppc = ppc
        self.delta_s = delta_s
        self.beta_buf = beta_buf      # 安全缓冲（米）

    def admits(self, plan, t0: float, pose: PoseCertificate,
               clearance_fn) -> tuple[bool, dict]:
        # (1) 截止期尾部：P(L <= D) >= 1 - delta_t
        if not self.lbc.admits():
            return False, {"reason": "deadline_tail",
                           "p_deadline": self.lbc.deadline_probability()}

        # (2) 在截止期 D 处（而非均值处）评估位姿管道
        X_pred, rho_D = self.ppc.tube(pose, self.lbc.D)

        # (3) 管道必须被几何净空支配
        clr = clearance_fn(plan, X_pred)          # 来自 CAC/ACSC
        if rho_D + self.beta_buf >= clr:
            return False, {"reason": "pose_tube", "rho_D": rho_D, "clr": clr}

        return True, {"X_pred": X_pred, "rho_D": rho_D,
                      "clr": clr, "margin": clr - rho_D - self.beta_buf}


# ============================================================
# IP-443 Temporal Coherence Fusion (TCF)
# ============================================================
class TemporalCoherenceFusion:
    def __init__(self, tau_skew: float, v_max: float):
        self.tau_skew = tau_skew
        self.v_max = v_max

    def fuse(self, certs: list, now: float) -> tuple[bool, dict]:
        # 1. TTL 检查：拒绝过期证书
        for c in certs:
            if now - c.t0 > c.ttl:
                return False, {"reason": "stale", "cert": c.name,
                               "age": now - c.t0, "ttl": c.ttl}
        # 2. 时间偏斜检查：拒绝"弗兰肯斯坦证书"
        t_min = min(c.t0 for c in certs)
        t_max = max(c.t0 for c in certs)
        skew = t_max - t_min
        if skew > self.tau_skew:
            return False, {"reason": "skew", "skew": skew,
                           "tau_skew": self.tau_skew}
        # 3. 偏斜转化为空间位移上界，计入管道
        delta_skew = self.v_max * skew
        return True, {"skew": skew, "delta_skew": delta_skew}


# ============================================================
# IP-444 Predictive Pose Extrapolation Certificate (PPEC)
# ============================================================
class PredictivePoseExtrapolationCertificate:
    def __init__(self, metric: 'SE3Metric', alpha: float = 1e-3):
        self.metric = metric
        self.alpha = alpha
        self.residuals = defaultdict(list)   # tau_bucket -> [d(X_pred, X_true)]

    def calibrate(self, X_pred, X_true, tau: float):
        bucket = round(tau / 0.005) * 0.005    # 5ms 分桶
        self.residuals[bucket].append(self.metric.distance(X_pred, X_true))

    def conformal_radius(self, tau: float) -> float:
        bucket = round(tau / 0.005) * 0.005
        rs = sorted(self.residuals.get(bucket, []))
        if len(rs) < 20:
            # 冷启动：退化为速度界（保守）
            return self._velocity_bound(tau)
        # 保形 (1-alpha) 分位数，含有限样本修正
        idx = min(len(rs) - 1,
                  int(math.ceil((len(rs) + 1) * (1 - self.alpha))) - 1)
        return rs[max(idx, 0)]

    def _velocity_bound(self, tau: float) -> float:
        # rho_motion <= v_max * tau（一阶），供无校准数据时兜底
        return self.v_max * tau


# ============================================================
# IP-445 Adaptive Latency–Pose Budget Allocator (ALPBA)
# ============================================================
class AdaptiveLatencyPoseBudgetAllocator:
    """在可选阶段间分配延迟预算，最大化净空余量。

    每个可选阶段 j: (cost_ms, d_eps_perc, d_eps_motion)。
    目标：在总预算 D - L_base 下，最大化减少的管道半径。
    0/1 背包；规模小（|S|<=8），可直接 DP。
    """
    def __init__(self, D: float):
        self.D = D

    def allocate(self, base_latency: float, stages: list[dict]) -> list[str]:
        budget = max(0.0, self.D - base_latency)
        # 以 1ms 为粒度做 DP
        W = int(budget)
        dp = [0.0] * (W + 1)
        choice = [[] for _ in range(W + 1)]
        for s in stages:
            c = int(s["cost_ms"])
            gain = s["d_eps_perc"] + s["d_eps_motion"]
            for w in range(W, c - 1, -1):
                if dp[w - c] + gain > dp[w]:
                    dp[w] = dp[w - c] + gain
                    choice[w] = choice[w - c] + [s["name"]]
        return choice[W]

class CertificateFederatedConsensusPlusPlusPlusPlus(
        CertificateFederatedConsensusPlusPlusHierarchical):
    def consensus_round(self, now: float, timeout=5.0):
        results = {}
        for key, votes in self.votes.items():
            count_ok = len(votes) >= self.N - self.F
            modalities = {v.modality for v in votes.values()}
            modality_ok = len(modalities) >= self.M_MIN_MODALITIES
            layer_ok = self._check_layer_consistency(votes)
            ce_ok = all(v.ce_version == votes[next(iter(votes))].ce_version
                        for v in votes.values())
            fs_ok = all(v.few_shot_valid for v in votes.values())
            ip_ok = all(v.ip_attested for v in votes.values())
            # 新增：时间对齐 + LPCC 票据
            tcf_ok, _ = TemporalCoherenceFusion(
                self.tau_skew, self.v_max).fuse(
                    [v.cert for v in votes.values()], now)
            lpcc_ok = all(v.lpcc_valid for v in votes.values())
            if all([count_ok, modality_ok, layer_ok,
                    ce_ok, fs_ok, ip_ok, tcf_ok, lpcc_ok]):
                results[key] = self._majority_with_outlier_filter(votes)
            else:
                results[key] = "CI"
        return results

        if not ok_tc:
            return False, {"reason": "tcf", **tc_info}
        # 3. 延迟—位姿耦合
        ok_lp, lp_info = self.lpcc.admits(plan, t0, pose_cert, clearance_fn)
        if not ok_lp:
            return False, {"reason": "lpcc", **lp_info}
        return True, {"tc": tc_info, "lpcc": lp_info}


# ============================================================
# 端到端：v24 流水线（在 v23 基础上插入时间层）
# ============================================================
class TemporalPoseAwarePipeline:
    def __init__(self, v23_pipeline, cfg):
        self.p23 = v23_pipeline
        self.lbc = LatencyBudgetCertificate(cfg["D"], cfg["delta_t"])
        self.ppec = PredictivePoseExtrapolationCertificate(cfg["metric"])
        self.ppc = PosePropagationCertificate(cfg["metric"], cfg["predictor"])
        self.lpcc = LatencyPoseCoupledCertificate(
            self.lbc, self.ppc, cfg["delta_s"], cfg["beta_buf"])
        self.tcf = TemporalCoherenceFusion(cfg["tau_skew"], cfg["v_max"])
        self.alloc = AdaptiveLatencyPoseBudgetAllocator(cfg["D"])

    def step(self, sensor, cloud_update=None):
        t0 = now_ms()
        # 1. 云边更新若会抬高延迟，先做"延迟感知切换门控"
        if cloud_update is not None:
            if self._switch_would_break_lpcc(cloud_update, t0):
                self.p23.cesc.defer_switch(cloud_update)
            else:
                self.p23.cesc.receive_cloud_update(
                    cloud_update["V"], cloud_update["artifacts"])

        # 2. 延迟预算分配（可选精化阶段）
        selected = self.alloc.allocate(self.lbc.expected(), sensor["stages"])
        sensor = self._apply_stage_selection(sensor, selected)

        # 3. 原有 v23 感知 + 证书生成
        admitted23, info = self.p23.step(sensor)

        # 4. 记录本步真实延迟
        latency = now_ms() - t0
        self.lbc.observe(latency)

        # 5. 位姿证书 + 时间融合 + LPCC
        pose_cert = sensor["pose_cert"]
        certs = sensor["certs"]
        ok_tc, tc_info = self.tcf.fuse(certs, t0)
        ok_lp, lp_info = self.lpcc.admits(
            info["plan"], t0, pose_cert, sensor["clearance_fn"])

        admitted = admitted23 and ok_tc and ok_lp
        return admitted, {
            "plan": info["plan"] if admitted else None,
            "v23": info,
            "tc": tc_info,
            "lpcc": lp_info,
            "latency_ms": latency,
            "regime": self.lbc.regime,
            "stages_selected": selected,
        }

    def _switch_would_break_lpcc(self, update, t0):
        # 切换窗口会引入 tau_switch 额外延迟 → 用 D + tau_switch 评估
        D_saved = self.lbc.D
        self.lbc.D = D_saved + self.p23.cesc.T_switch * 1000.0
        ok = self.lbc.admits()
        self.lbc.D = D_saved
        return not ok
```

## 3. 正确性论证

### 引理 1（位姿管道分解）
**陈述**：设 $\hat X(t_0)$ 满足 $d(\hat X(t_0),X(t_0))\le\varepsilon_{\text{perc}}$，外推误差满足 $d(\tilde X(t_0+\tau), X(t_0+\tau))\le\varepsilon_{\text{motion}}(\tau)$ 由 PPEC 校准，运动学标定误差 $\le\varepsilon_{\text{kin}}$。则
$$d(\tilde X(t_0+\tau),X(t_0+\tau))\le\varepsilon_{\text{perc}}+\varepsilon_{\text{motion}}(\tau)+\varepsilon_{\text{kin}}.$$

**证明**：取左不变度量 $d$，由三角不等式拆成"估计→真值"、"外推→真实运动"、"标定偏差"三段；左不变性保证 $d(G A,G B)=d(A,B)$，使各段误差可在同一 twist 范数下相加。三项分别由 SDC/DCSC、PPEC、ACSC 提供上界，相加即得。∎

### 引理 2（截止期尾部塌缩）
**陈述**：若 $\varepsilon_{\text{motion}}(\tau)$ 关于 $\tau$ 单调不减，且 $L\le D$ 在通过 LBC 的事件上成立，则
$$e_{\text{total}}(L)\le \rho(D).$$
因此只需在 $\tau=D$ 处评估管道即可保证任意 $L\le D$ 的安全性。

**证明**：由单调性 $\varepsilon_{\text{motion}}(L)\le\varepsilon_{\text{motion}}(D)$，代入引理 1 得 $e_{\text{total}}(L)\le\varepsilon_{\text{perc}}+\varepsilon_{\text{motion}}(D)+\varepsilon_{\text{kin}}=\rho(D)$。∎

> **注记**：若单调性不成立（学习型预测器在长尾处非单调），则须改为 $\sup_{\tau\in[0,D]}\rho(\tau)$，保守度上升但结论仍成立。这构成本轮最大风险的理论根源。

### 引理 3（时间一致性把偏斜转为空间界）
**陈述**：若 $\mathrm{TCF}(\mathcal C)$ 成立，则融合证书之间因时间偏斜引入的额外位姿误差 $\le\delta_{\text{skew}}=v_{\max}\tau_{\text{skew}}$。

**证明**：任意两张证书时间差 $\Delta t\le\tau_{\text{skew}}$，末端速度有界 $v_{\max}$，则位移 $d(X(t),X(t+\Delta t))\le v_{\max}\Delta t\le v_{\max}\tau_{\text{skew}}$。TTL 检查排除超出存活期的过期证书，故融合状态的时空错位被 $\delta_{\text{skew}}$ 界住。∎

### 引理 4（延迟感知切换保持单调）
**陈述**：若 CESC 切换仅在以 $D+\tau_{\text{switch}}$ 评估 LPCC 仍通过时执行，则 $\mathrm{Exec}_{v24}\subseteq\mathrm{Exec}_{v23}$。

**证明**：切换门控拒绝任何会使 LPCC 失效的更新，故执行集只会因新增 $\mathrm{Fil}_{\text{lpcc}}\cap\mathrm{Fil}_{\text{tc}}$ 而收缩；v23 的既有证书条件未被放宽，交集单调。∎

### 定理（HPC-E++ 时空准入门可靠性）
**陈述**：若 $\mathrm{HPCEPlusPlus.admits}$ 在 $t_0$ 返回真，则执行区间 $[t_0,t_0+D]$ 内碰撞概率 $\le\delta_t+\delta_s+\delta_{\text{coh}}$。

**证明**：准入为四个连言：v23 四证（由 v23 定理保证物理/合规/专利安全）、TCF（引理 3，违约概率 $\le\delta_{\text{coh}}$）、LBC（$P(L>D)\le\delta_t$）、LPCC（在 $L\le D$ 事件下管道越界概率 $\le\delta_s$，由引理 1、2）。对"截止期违约""管道越界""时间一致性违约"三个坏事件取并集界，得总失效概率 $\le\delta_t+\delta_s+\delta_{\text{coh}}$。∎

## 4. 已知风险与缓解

| 编号 | 描述 | 严重度 | 缓解措施 | 剩余风险 |
|---|---|---|---|---|
| R1 | 外推误差非单调：学习型预测器在长尾延迟处"蒙对"，使"尾部即最坏"塌缩失效 | 最高 | 1) 在线检验 $\varepsilon_{\text{motion}}(\tau)$ 单调性（分桶残差做趋势检验）；2) 不满足时改用 $\sup_{\tau\le D}\rho(\tau)$；3) 预测器输出附单调性证书 | 上确界评估会显著提高保守度，导致可用性下降 |
| R2 | 延迟分布非平稳：云边切换/网络抖动造成 burst，历史尾部估计失效 | 高 | 1) LBC 机制切换检测（steady/burst）；2) 切换窗口内用 $D+\tau_{\text{switch}}$ 评估；3) 极端时冻结切换、退回本地预测 | burst 持续时间超过样本窗口时，Clopper-Pearson 下界仍可能高估 |
| R3 | SE(3) 度量选择依赖坐标：左不变度量非双不变，误差界随参考系漂移 | 高 | 1) 固定左不变度量并在证书中记录参考系；2) 对关键净空方向做局部坐标重投影；3) 与 ACSC 的欧氏膨胀取更保守者 | 大角度旋转时 twist 范数与欧氏距离差异显著，可能低估平移分量 |
| R4 | 异步证书融合的时间偏斜导致"弗兰肯斯坦证书" | 中 | TCF 强制 TTL + $\tau_{\text{skew}}$；超限即拒证并触发重采样；关键证书（位姿/障碍）同步签发 | 高动态场景下频繁拒证会降低任务成功率 |
| R5 | ALPBA 背包分配在预算边缘震荡，造成阶段频繁切换 | 中 | 1) 分配结果加滞回（hysteresis）；2) 每次切换需连续两帧同向；3) 安全优先：净空余量低于阈值时禁用可选精化 | 滞回增加响应延迟，极端时错过最佳精化窗口 |

## 6. 本轮最大风险（最终确认）

**一句话**：把延迟当作可加的空间误差、并只在截止期处评估，其正确性依赖"外推误差随延迟单调"与"延迟分布平稳"；一旦学习型预测器在长尾延迟下非单调、或云边切换使延迟分布突变，"尾部即最坏"的塌缩会失效，证书将在真实执行时低估位姿误差。
