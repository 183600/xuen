# 第 1 轮（灵感循环 v2：「跨物体泛化」×「伦理审查」）—— 从「平均成功率」转向「稀有风险类的不可补偿泛化」

> **承接与改写。** 上一轮 UIP-01~10 的三条边界判断仍然成立：选手只能提交一个远端 `observation→action` API；单模型多任务；排名看成功率与步骤分。但上一轮有一个**被工作区榜单快照推翻的隐含假设**：它把「步骤分」当成可与成功率分开优化的独立杠杆。8 模型 × 32 任务的快照显示 `step ≈ 0.51 + 1.321·success`（R²=0.981），步骤分几乎完全由成功率线性决定。真正被平均值掩盖的，不是步骤分，而是**稀有物体类与高风险物体类的尾部失败**。本轮因此不新增一个并列功能点，而是**重写目标函数与状态表示**：用「跨物体泛化」定义「对什么做留一」，用「伦理审查」定义「什么样的失败不可被平均」。

## 0. 先给直觉，再给严谨定义

### 0.1 跨物体泛化：直觉

一个策略在训练里见过 16 种杯子；遇到第 17 种杯子时，若它记住的是「红色圆柱、高 9cm、出现在画面左下」，它会失败；若它学到的是「可抓握、可套叠、开口要对准架子」，它更可能成功。

**一句话直觉：跨物体泛化不是把模型做大，而是让策略以「物体能做什么」而不是「物体长什么样」为条件。**

**严谨定义。** 设物体类集合 `O`，训练可见类 `O_s`、评测未见类 `O_n`（按**物体类**留一，而非按样本随机划分）。策略 `π` 在类 `o` 上的成功率为 `S_o(π)`、伤害率为 `H_o(π)`。定义

- 平均泛化间隙 `G_mean(π) = mean_{o∈O_s} S_o − mean_{o∈O_n} S_o`；
- 最坏类间隙 `G_wc(π) = min_{o∈O_s} S_o − min_{o∈O_n} S_o`；
- 留一类风险 `R_loo(π) = max_{o∈O_n} (1 − S_o(π))`。

跨物体泛化的真正目标是压缩 `G_wc` 与 `R_loo`，而不是最大化平均 `S`。随机样本划分会把同一物体的相邻帧分到训练与测试，系统性低估 `G`；因此评测协议必须是 **OCLOO（Object-Class Leave-One-Out）**。

### 0.2 伦理审查：直觉

伦理审查（IRB）不是「先给研究打分，再按分数扣罚」，而是**不可补偿的准入条件**：一项研究哪怕科学价值极高，只要违反知情同意，就不得开展；高分不能赎买违规。机器人策略同理：药品、注射器、电池、市电插头、玻璃试管、尖锐工具上的伤害率，**不能**与安全物体上的高成功率做加权平均。

**一句话直觉：伦理审查是可行性约束，不是惩罚项。**

**严谨定义。** 把物体按风险类别划分 `R ⊂ O`（medicine / sharps / mains / liquid / brittle）。策略 `π` 的伦理可行集为

`Π_α = { π : ∀ o ∈ R, H_o(π) ≤ α }`。

目标为 `max_{π ∈ Π_α} mean_o S_o(π)`，并以最坏类成功率作次级 tie-break。注意约束是 `∀`（等价于 `max_o H_o ≤ α`）而不是 `mean_o H_o ≤ α`：这是**非补偿（non-compensatory）**约束。任何「用安全类高分抵消高风险类伤害」的加权目标，都会在分布偏移下退化为冒险策略。

### 0.3 交叉点：本轮核心直觉

工作区任务资料显示：32 个任务中 **23 个**明确写了「未见物体」，其中 **6 个同时属于高风险类**（T05 拔网线、T10 插充电器、T11 取电池、T13 试管、T14 倒药、T26 插网线）。也就是说，**泛化最弱的地方恰好是伦理最敏感的地方**。于是本轮不是两个并列想法，而是一个联合命题：

> **在物体类留一分布上最大化平均成功率，同时满足「每个高风险物体类的伤害率 ≤ α」这一不可补偿约束。**

## 4. 方案骨架：XOG-ER

**XOG-ER = Cross-Object Generalization with an Ethics-Review gate**，三个部件：

1. **物体槽位表示（OCLOO-Afford）**：把语言指令与多视角观测解析为 `(角色, 可供性, 关系)` 槽位，动作先验条件化在槽位上而非外观 ID；训练时按物体类留一，强制模型依赖可供性。
2. **不可补偿风险闸（NEG）**：对每个高风险物体类估计伤害率的单侧置信上界；若激进动作的 `LCB(H) > α`，切换到保守已验证子程序；若保守子程序仍超限，则弃权/安全保持。它是**硬过滤**，不是扣分项。
3. **滚动复核与红队（RRC）**：每 `k` 步复核一次槽位与风险估计；上线前对 9 个高风险任务做红队；每轮评测后做失败审计并回滚。

**为什么仍在选手权限内：** 全部逻辑都在 `get_action`/`reset` 内部，只依赖 observation、语言与自身维护的 episode 状态；不触碰电机、ROS 或评测执行栈。

## 5. 与「补一个功能点」的区别

- 常规做法在**平均成功率**上做梯度；XOG-ER 在**类级最坏情况**上做可行性筛选，再在可行集内最大化平均。
- 常规「安全惩罚」是 `score − λ·harm`，权重 `λ` 依赖未知部署分布；XOG-ER 用可解释的 `α` 直接定义不可行集，**高分不能赎回违规**。
- 常规跨物体泛化只做数据增广；XOG-ER 同时改变**评测协议**（OCLOO）与**推理条件**（槽位）。

## 6. 本轮最大风险

**一句话：如果高风险物体的伤害率估计器本身不校准（漏检「未见的危险物体」或把安全物体误判为危险），那么「不可补偿闸」只会把错误从「冒险」换成「误弃权」——纸面上的 0 违规并不等于真实安全，必须用独立校准集与红队审计证明 `α` 的可信度。**

## 1. 形式化

### 1.1 符号

- `O`：物体类集合；`O_s` 可见类，`O_n` 未见类（按类留一）。
- `R ⊂ O`：高风险类（medicine / sharps / mains / liquid / brittle）。
- `π`：策略（一个远端 API 服务）；`S_o(π)`、`H_o(π)`：类 `o` 上的成功率与伤害率。
- `A`：动作块；`k`：承诺步数；`α`：每类伤害率上限；`δ`：置信水平参数。

### 1.2 目标

```
maximize   mean_{o∈O} S_o(π)
subject to ∀ o ∈ R : H_o(π) ≤ α          (不可补偿)
           min_{o∈O} S_o(π) ≥ β          (可选的最坏类下限)
```

与排行榜的「成功率 + 步骤分」并不冲突：步骤分在快照中约等于 `0.51 + 1.32·S`，所以提升 `S` 也提升步骤分；但**只有在 `Π_α` 内的 `S` 才计分**，否则再高的平均也视为不可提交。

### 1.3 为什么加权惩罚不能替代硬约束（简短推导）

把部署分布压成两类：安全类 `A`（占比 `1−ε`，很大）与风险类 `B`（占比 `ε`，很小）。设激进动作相对保守动作给 `A` 增加 `b_A > 0`、给 `B` 增加 `b_B > 0` 的成功收益，但在 `B` 上造成 `H_B > α` 的伤害。补偿型目标

`J(π) = (1−ε)·[S_A − λ·H_A] + ε·[S_B − λ·H_B]`

选择激进动作的条件近似为

`(1−ε)·b_A + ε·b_B > λ·[(1−ε)·ΔH_A + ε·ΔH_B]`。

当 `ε → 0` 时，风险类在目标中的权重趋于 0，**只要 `b_A` 足够大，激进在 `B` 上违规仍然最优**。因此不存在一个与部署分布无关的固定 `λ` 能保证 `∀o H_o ≤ α`。非补偿闸的做法是先做可行性过滤 `π ∈ Π_α`，再在可行集内比较 `mean S`；代价是必须能可靠估计 `H_o`（见 §6 的风险）。

### 1.4 有限样本下的可行性

真实 `H_o` 未知，用单侧置信上界 `Ĥ_o^+ = Ĥ_o + z_{1−δ}·sqrt(Ĥ_o(1−Ĥ_o)/n_o)`。闸门规则：

```
若 ∀o∈R: Ĥ_o^+(aggressive) ≤ α  → 允许激进
否则若 ∀o∈R: Ĥ_o^+(conservative) ≤ α → 切保守子程序
否则 → 弃权 / 安全保持（handoff）
```

在估计器校准良好的前提下，以至少 `1−δ` 的概率满足真实约束。**校准误差是唯一的破防点**，因此 `δ`、`n_o` 与校准集必须一起报告。

## 3. XOG-ER 架构与伪代码

```python
SAFE_HOLD = object()  # 保持当前位置、不产生伤害的保持动作

class XOGER:
    def __init__(self, policy, conservative, perceive, risk_class,
                 harm_lcb, alpha=0.02, k=4, n_min=80):
        self.policy, self.conservative = policy, conservative
        self.perceive, self.risk_class = perceive, risk_class
        self.harm_lcb = harm_lcb            # 单侧 LCB，输入 (slots, mode)
        self.alpha, self.k, self.n_min = alpha, k, n_min
        self.reset()

    def reset(self):
        self.buf, self.slots = [], None
        self.step = 0
        self.policy.reset(); self.conservative.reset()

    def get_action(self, obs):
        self.step += 1
        if self.slots is None or not self.buf or self._low_confidence(obs):
            self.slots = self.perceive(obs, obs["observation.language"])
            self.buf = self._gated_chunk(obs)
        return self.buf.pop(0)

    def _gated_chunk(self, obs):
        chunk = self.policy.act(obs, self.slots)          # 激进候选块
        active_risk = [o for o in self.slots.targets
                       if self.risk_class(o) == "high"]
        if not active_risk:
            return list(chunk[:self.k])
        # 非补偿：任一风险类的伤害 LCB 超限，就不能激进
        for o in active_risk:
            if self.harm_lcb(self.slots, o, mode="aggressive") > self.alpha:
                if self.harm_lcb(self.slots, o, mode="conservative") <= self.alpha:
                    return list(self.conservative.act(obs, self.slots)[:self.k])
                return [SAFE_HOLD] * self.k           # 弃权 / 请求人工
        return list(chunk[:self.k])

    def _low_confidence(self, obs):
        # 只在槽位漂移或风险类不确定时触发重感知，避免逐帧 VLM 延迟
        return self.slots.confidence < 0.6 or self.slots.risk_uncertain
```

**三道保险，各管一件事：**

1. `k`-步承诺：避免整块盲走（承接 UIP-01）。
2. 槽位条件：让动作依赖「可供性/关系」而非外观 ID（XIP-1）。
3. `∀o H_o ≤ α` + 保守/弃权：把最坏类伤害变成硬约束（XIP-2），而不是事后扣分。

**与 UIP-01 的关键差异：** UIP-01 用 VLM 判断「子目标是否完成」；XOG-ER 用槽位与风险估计判断「**该不该以激进模式继续**」，VLM 只在低置信时触发。这样既保留迭代验证，又避免上一轮自己识别的「逐帧 VLM 延迟方差」风险。

| **E2** 槽位条件化 | 外观 ID 条件 vs 可供性/关系槽位 | 未见类成功率、`G_wc` | 槽位条件把 `G_wc` 至少缩小 30%（以 E1 同切分为准） |
| **E3** 补偿 vs 非补偿 | 线性惩罚 `λ`（含按部署频率加权）vs 硬闸 | 每风险类伤害率、违规数、平均分 | 存在 `λ` 使平均分更高但仍有 ≥1 个风险类违规；硬闸以 ≤10% 分数代价换 0 违规 |
| **E4** 风险×未见 2×2 | 6 个风险∩未见任务 vs 其余 | 四格成功率/伤害率 | 硬闸的收益集中在「风险∩未见」格；若均匀分布，则 XIP-2 的动机不成立 |
| **E5** 校准与漏检 | 不同 `n_o`、`δ`、校准集来源 | 估计器 ECE、false-safe rate（把危险判成安全） | ECE > 0.05 时违规率显著上升；需独立校准集 |
| **E6** 端到端 | 基线单模型 vs XOG-ER | 平均成功率、最坏类成功率、`max_o H_o` | 预注册：最坏类成功率 +Δ，`max_o H_o` 下降且平均分损失有界 |

> 所有「真机」结论在正式提测前一律标注为**代理指标**（回放 + 合成风险标注），不得当作真机结论。E4 的 2×2 设计是本轮最关键的判别实验：它决定「伦理审查」是不是一个独立贡献，还是只是安全团队的常规检查。

## 5. 玩具校准结果（合成，不是机器人数据）

脚本：`workspace/exp/coat_er_sim.py`；结果：`workspace/exp/coat_er_results.json`。24 个合成物体类（16 可见 / 8 未见），`α=0.02`，`risk_violations` 统计「有多少个 `(seen/novel)×(normal/risk)` 组的伤害率超过 `α`」。

| 配置 | 平均成功 | 平均分 | 未见间隙 | 最坏组成功 | 最大组伤害 | 违规组数 |
|---|---|---|---|---|---|---|
| 外观绑定 + 激进 | 83.7% | 129.8 | 25.3pp | 60.4% | 84.8% | 3 |
| 可供性绑定 + 激进 | **92.8%** | **143.9** | **4.7pp** | **88.7%** | 84.8% | 3 |
| 可供性 + 线性惩罚（λ=200） | 90.0% | 130.3 | 4.7pp | 77.1% | 5.5% | 1 |
| 可供性 + 按部署频率加权惩罚（风险权重 0.15） | **92.8%** | **143.9** | 4.7pp | 88.7% | 84.8% | **3** |
| 可供性 + 非补偿硬闸（α=0.02） | 87.8% | 121.4 | 15.4pp | 77.1% | **1.8%** | **0** |

读法（严格）：

1. **外观 → 可供性**：未见间隙从 25.3pp 降到 4.7pp，最坏组从 60.4% 升到 88.7%——跨物体泛化的机制有效（合成）。
2. **平均成功高 ≠ 安全**：前两行的最大组伤害都是 84.8%，但平均分最高；这正是排行榜「平均值」会奖励的行为。
3. **按部署频率加权的惩罚几乎无效**：风险类只占 15% 权重时，它与激进配置完全同分布（3 个违规组）——对应 §1.3 的「`ε→0` 时补偿失效」。
4. **非补偿硬闸以 5pp 平均成功、22.5 平均分换 0 违规**；代价是未见间隙回升到 15.4pp（因为对新物体更保守）。这是**可解释的取舍**，不是免费的午餐。

### 5.1 α 与 λ 的敏感性（同一合成数据）

| α | 平均分 | 最大组伤害 | 违规组数 |
|---|---|---|---|
| 0.005 | 121.4 | 1.8% | 0 |
| 0.02 | 121.4 | 1.8% | 0 |
| 0.05 | 130.3 | 5.5% | 1 |
| 0.10 | 130.3 | 5.5% | 1 |

| λ（线性惩罚） | 平均分 | 最大组伤害 | 违规组数 |
|---|---|---|---|
| 0 | 143.9 | 84.8% | 3 |
| 200 | 130.3 | 5.5% | 1 |
| 800 | 125.9 | 2.1% | 1 |
| 1600 | 121.4 | 1.8% | 0 |

**结论：** 一个「事后调对」的线性惩罚在 `λ=1600` 时也能达到 0 违规，和硬闸同分；但 `λ` 依赖部署权重，换分布就失效（见加权行）。硬闸的优势是**用有语义的 `α` 替代不可解释的 `λ`**，并把成本局部化到风险类。

## 6. 最大的方法论风险与缓解

1. **伤害标签缺失**：公开数据只有成功/失败，没有「伤害」标签。缓解：用物体语义构造风险类，再做小规模人工复核；把 `H_o` 作为**代理指标**报告，并附红队视频审计。
2. **风险估计器漏检未见危险物体**：这是本轮最大破防点（见 §1.4 与想法区 §6）。缓解：独立校准集 + 单侧 LCB + `α` 敏感性 + 对「低置信」一律走保守/弃权。
3. **弃权被误当成失败**：弃权可保护安全但拉低成功率。缓解：把弃权计入步骤分的最小保底动作，并在提交前明确「安全优先」的取舍。
4. **合成与真机脱节**：§5 只是机制可计算性校准，不是性能承诺。缓解：E4 的 2×2 真机/回放判别是 go/no-go 门。
