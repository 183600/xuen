# 第 68 轮（承接第 67 轮「SimRAS 仿真增强风险闭环」IP-233~242；灵感循环第 1 轮（新循环）；本轮灵感：「用户需求分析」×「多机器人协作」）

> 第 65~67 轮（VISTA→RAS→SimRAS）共享一条从未被挑战的公理：**任务与需求是外部给定的常量，而且这个常量是对的**。VISTA 问「哪一层坏了」，RAS 问「谁控制、控制多少」，SimRAS 问「未来怎么坏」——三者都在优化一个**已经被写好的目标函数**。可真实部署里最先出错的往往不是执行，而是目标本身：需求没被说全、说错、说话间又变了；或者多台机器人对同一句话的理解并不相同。
>
> 本轮的核心命题是：
>
> **把「需求」从外部给定的常量，升级为一个必须被主动估计、团队协商、并持续认证的隐变量；把「单机安全证书」升级为「以团队共识需求为参照系的组合式证书」。**
>
> 命名 **CONCERT（Collaborative Objective Negotiation with Certified Embodied Robot Teams，需求共识与认证协同）**。它不再只问「这个动作安不安全」，而是问：**「我们此刻执行的目标，真的是用户要的吗？团队里每个成员相信的是同一个目标吗？如果都错了，谁能把它证伪？」**

## 0. 直觉与动机

**灵感 1（用户需求分析 → 需求是被测量出来的，不是被读取出来的）**
直觉：传统任务规划假设 `task = given`。但用户需求分析的第一课是：需求是**欠定的、情境依赖的、并且会被提问方式反向塑造的**。你问「你要快还是稳？」，用户可能随口选「稳」，但这不等于他心里真的把稳定性排在速度之前。于是安全系统优化的是一个**被测量过程污染过的 θ**。这把「感知噪声」从传感器层面上升到了**目标层面**：最危险的噪声不是"我把距离测错了"，而是"我把用户想要什么测错了"。移动机器人做错事可以被急停兜底；做错**目标**却往往在很久以后才被发现，而且没有任何一条现有证书会报警。

**灵感 2（多机器人协作 → 需求是一个需要共识的共享隐变量）**
直觉：单机时，需求后验 `Q(θ)` 只需要自己相信。多机时，每台机器人都有自己的 `Q_i(θ)`；它们共享的传感器不同、看到的人不同、先验也不同。若 `Q_1` 认为用户要「快速穿过」，`Q_2` 认为用户要「保持距离」，两台机器人会**各自拿着对同一任务的合法证书**做出彼此不兼容的动作：一台加速逼近、一台减速后退，组合起来的联合轨迹谁都没有认证过。这就是**需求接缝（need seam）**：不是几何证书断了，而是**证书所参照的目标断了**。因此协作安全的第一性对象不是"每台机器人的安全集"，而是**「团队共识需求 × 联合状态」上的组合证书**。

**灵感 3（交点 → 主动询问的悖论与需求可证伪性）**
直觉：既然需求要测，那是不是问得越多越好？不是。每一次询问都有三重代价：
1. **认知成本**：打断用户、消耗注意力；
2. **锚定反作用**：问法会把用户推向某个选项，测到的需求因此偏移；
3. **安全成本**：有些询问需要机器人"展示两个方案"，展示本身要移动，移动就要证书。
于是存在一个**最优询问率** `λ_q*`：信息增益随询问次数边际递减，而成本近似线性，越过某点后**问得越多，真实效用越低**。更关键的是，安全系统必须能**证伪需求本身**：当团队的行为与用户后续反馈系统性不符时，要能主动怀疑"我们理解错了目标"，而不是继续"安全地做错事"。这把 VISTA 的「先验可证伪」推进到第三层：**参数可证伪 → 故障可证伪 → 需求可证伪**。

**灵感 4（反直觉 → 共识不等于正确，团队会放大共因错误）**
直觉：通常认为「多台机器人交叉验证会更可靠」。但如果它们共享同一套训练数据、同一个基础模型、同一种先验，它们的误差就是**相关的**。设单台证据量 `N`、机器人数量 `n`、证据相关系数 `ρ_c`，则团队有效独立证据量为
`N_eff = nN / (1 + (n-1)ρ_c)`。
当 `ρ_c → 1`，`N_eff → N`：**加多少台机器人都等于一台**。此时 `D_team = max_i KL(Q_i || Q̄)` 会很小，但 `Q̄` 可能离真值很远——团队"高度一致地错"。这是本轮最值得写进理论的结论：**需求分歧可以被共识协议压平，但被压平的分歧不会消失，只会从"显性争吵"变成"隐性共因错误"**。所以 CONCERT 必须保留"故意制造分歧"的机制（反事实探针、独立证据通道），否则共识协议会亲手制造虚假信心。

**灵感 5（对前三轮的升级点）**
- **VISTA 的故障归因** → 需求层归因：新增 `H_need_wrong`（目标理解错）、`H_need_split`（团队理解分裂）、`H_need_drift`（需求漂移）、`H_need_anchor`（询问诱导）；
- **RAS 的 λ_risk** → 增加需求项：`λ_need = 1 - α_n·H(Q̄) - β_n·D_team`；需求越不确定、团队越分裂，认证前缀越短；
- **SimRAS 的世界模型** → 升级为**多智能体联合世界模型**：新增 `other_robot_head`、`human_need_head`，WM 既要预演物理，也要预演"别人会怎么理解需求"；
- **SimRAS 的 VQA 审计** → 升级为**需求审计**：不再只问"这安全吗"，而问"这满足用户说的需求吗？哪些反事实下会不满足？哪台机器人在按另一个理解行动？"；
- **J 证书** → 增加 `need_hash / need_posterior / need_divergence / consensus_ver / role_assign_hash / query_budget_used`，使「共识是否可信、需求是否被证伪」可审计。

## 1. 形式化定义（增量：定义 266–285）

- **定义 266（CONCERT 总览）**：`CONCERT = (UNC, RES, QEC, CCT, ROLE, DDA, NVA, JWM, AIC-MC, J_CONCERT)`。定位：把 VISTA/RAS/SimRAS 的「目标给定、单机、执行层安全」，升级为「目标隐变量、团队共识、需求层可证伪」的协作闭环。不变式：需求推断、证据融合、询问选择、共识协商、组合证书、需求审计只在语义流/后台；实时流只做需求后验的查表、团队前缀判定、分歧早停与安全回退，零学习写操作。
- **定义 267（潜需求空间）**：潜在需求 `θ ∈ Θ ⊂ ℝ^d`（`d ≤ 8`），参数化一个效用-约束对 `(U_θ, C_θ)`：`U_θ: (ξ_{0:T}, a_{0:T}) → ℝ`，`C_θ` 为一族安全性/偏好约束。任务"被满足"当且仅当 `E[U_θ] ≥ u_min(θ)` 且 `C_θ` 成立。`θ` 不可直接观测，只能通过询问、行为观测与任务上下文间接推断。
- **定义 268（需求后验）**：机器人 `i` 维护 `Q_i(θ) ∝ Q_i^0(θ) · ∏_{e ∈ E_i} ℓ_e(θ)`，其中 `ℓ_e` 为一条证据（显式回答、被动行为、上下文先验）的似然。`E_i` 为机器人 `i` 的证据集。
- **定义 269（询问与证据算子）**：询问集 `Q_q = {q_1, …, q_m}`，每条询问 `q` 产生回答 `y_q ~ P(y | θ, q)`。询问的**认知成本** `c_cog(q)`（打断时长、交互步数），**锚定成本** `c_anchor(q)`（问法对后验的诱导偏移），**安全成本** `c_safe(q)`（为展示选项而移动所需的证书长度）。
- **定义 270（主动询问目标）**：`q* = argmax_{q ∈ Q_q, s.t. Cert(q)} [ I(θ; y_q | Q̄) − c_cog(q) − c_anchor(q) − c_safe(q) ]`，其中 `I(θ; y_q | Q̄) = H(Q̄) − E_{y_q}[H(Q̄ | y_q)]`，`Q̄` 为团队共识后验（定义 272）。`Cert(q)` 表示该询问本身通过证书（定义 276）。
- **定义 271（需求分歧）**：`D_team = max_i KL(Q_i || Q̄)`，`D_pair = max_{i<j} KL(Q_i || Q_j)`。当 `D_team > τ_need` 时触发**需求分裂告警** `H_need_split`，冻结新承诺并进入共识轮。
- **定义 272（共识算子与共享证据日志）**：`Q̄ ∝ exp( Σ_i w_i · log Q_i )`（对数意见池），其中鲁棒权重 `w_i ∈ [0,1]` 由证据可靠性/拜占庭检测给出，`Σ_i w_i` 归一化。共享证据日志 `L_shared = Σ_i w_i log ℓ_i`；只有写入 `L_shared` 的证据才可跨机器人复用。`Q̄` 是**组合证书的唯一参照系**——绝不允许各机器人用自己的 `Q_i` 单独认证。
- **定义 273（组合式团队证书）**：对联合动作剖面 `a = (a_1, …, a_n)`，`J_team = (J_1, …, J_n, Q̄, D_team, L_shared_hash, ρ, comm_hash)`。`J_team` 有效当且仅当：1) `∀i, J_i` 相对 `Q̄` 有效；2) `∀i<j, m_ij(a_i, a_j) ≥ 0`（机器人体间裕度）；3) `∀i, m_{i,h}(a_i) ≥ 0`（对人裕度）；4) `D_team ≤ τ_need`；5) `comm_hash` 全队一致。
- **定义 274（需求条件下的鲁棒角色分配）**：角色 `ρ: {1..n} → ROLES`。credal 集 `C_ε(Q̄) = {θ : KL(θ || Q̄) ≤ ε}`。鲁棒分配 `ρ* = argmax_ρ min_{θ ∈ C_ε(Q̄)} E[U_θ | ρ]`，且要求 `∀θ ∈ C_ε, C_θ` 成立。当 `C_ε` 上界与下界的效用差 `ΔU(ρ) > τ_role` 时，标记角色对需求"敏感"，必须优先择清需求再分配。
- **定义 275（需求漂移）**：用 CUSUM 监测新证据对旧后验的对数似然比：`S_t = max(0, S_{t-1} + log ℓ_t(θ̂_t) − log ℓ_t(θ̂_{t-1}))`。`S_t > h` 时触发 `H_need_drift`，重置共识、上调询问率、缩短认证前缀。
- **定义 276（询问证书 / 询问前缀）**：询问 `q` **非扰动**当且仅当询问期间联合状态始终停留在已认证安全集内（例如原地提问、仅语音交互）；**扰动询问**（需移动展示选项）必须携带自己的认证前缀 `k_q`，并满足与主动作链的接缝重叠 `o_q ≥ 0`。
- **定义 277（需求可证伪探针）**：反事实探针是一对安全的小动作 `(a^+, a^-)`，使得 `U_θ(a^+) > U_θ(a^-)` 当且仅当 `θ ∈ Θ_A`。执行探针并观测用户反应/后续行为，得到对 `Θ_A` 的一次判别性证据。定义**需求可证伪率** `f_need = P(存在探针使错误需求被拒)`。
- **定义 278（多智能体联合世界模型 JWM）**：`JWM_φ = (Enc, dyn_head, emo_head, fault_head, other_robot_head, human_need_head)`。`other_robot_head` 预测队友动作/信念，`human_need_head` 输出 `θ` 的后验演化。损失 `L = L_recon + λ_e L_emo + λ_f L_fault + λ_o L_other + λ_n L_need + λ_c L_consensus`，其中 `L_consensus` 惩罚与 `L_shared` 不一致的独立幻觉。
- **定义 279（需求审计员 NVA）**：`NVA = (Render, VQA, PromptTpl, StructParser)`。对 JWM 渲染的团队滚动视频提出三类问题：需求满足性（"这是否满足 `<θ̂ 渲染出的需求陈述>`"）、反事实敏感性（"若用户更看重 X 而非 Y，这段行为会怎么变"）、理解一致性（"是否有机器人在按不同理解行动"）。输出 `NeedAudit = {satisfied, counterfactual_flips, divergence_flags, need_adjust}`。
- **定义 280（AIC-MC 干扰与共因）**：`ℰ_MC = ℰ_SimRAS × ℰ_need × ℰ_consensus × ℰ_evidence`。其中 `ℰ_need = {需求欠定, 需求漂移, 询问锚定, 用户误报}`，`ℰ_consensus = {通信延迟/丢包, 拜占庭机器人, 权重坍缩}`，`ℰ_evidence = {证据相关, 共享盲点, 数据集偏置}`；并建共因 `ℰ_common_need`（同一训练分布使全队共享同一错误先验）。
- **定义 281（J_CONCERT 证书）**：`J_CONCERT = (J_SimRAS, need_hash, need_posterior_digest, need_divergence, consensus_ver, role_assign_hash, query_budget_used, falsify_rate, drift_flag)`。`Valid ⇔ Valid(J_SimRAS) ∧ D_team ≤ τ_need ∧ f_need ≥ f_min ∧ (drift_flag = False ∨ 已重认证)`。
- **定义 282（团队认证前缀）**：`k*CONCERT = min(k_VISTA, k_emo, k_wm, k_need, k_role, m_team)`，其中 `k_need` 为需求后验在滚动视界内保持 `D_team ≤ τ_need` 的步数，`k_role` 为鲁棒角色分配仍成立（`ρ*` 不变）的步数。
- **定义 283（共识收敛条件）**：设各机器人证据似然的对数凹性常数 `L_i`、通信拓扑的代数连通度 `λ_2`。若每轮交换充分统计量且 `λ_2 > 0`，则 `D_team(t) ≤ D_team(0)·exp(−λ_2·t / L_max) + ε_comm`。即分歧以拓扑速率指数收敛，但存在由通信噪声决定的残差下界 `ε_comm`——**残差意味着共识永远不会自动变成正确**。
- **定义 284（需求层风险缩放）**：`λ_need = 1 − α_n·H(Q̄) − β_n·D_team − γ_n·1[drift_flag]`，裁剪到 `[0.4, 1.0]`。最终控制增益 `λ = λ_risk · λ_need`。需求越不确定、团队越分裂、漂移越可疑，控制越保守。
- **定义 285（在线部署不变式）**：实时流只做：需求后验查表、`D_team ≤ τ_need` 布尔判定、`k*CONCERT` 截断、`λ_need` 乘法、安全回退。后验更新、共识轮、询问选择、组合证书、需求审计全部在语义流/后台；离线标定 `τ_need, α_n, β_n, h, f_min` 与 JWM 预训练。

# UNC：需求制图器（后验维护 + 询问选择）
class UserNeedCartographer:
    def __init__(self, theta_space, tau_need=0.2):
        self.Theta, self.tau_need = theta_space, tau_need
        self.Q = theta_space.uniform_prior()

    def update(self, evidence):
        for e in evidence:
            self.Q = normalize(self.Q * e.likelihood(self.Theta))
        return self.Q

    def expected_info(self, q):
        return entropy(self.Q) - expected_entropy_after(self.Q, q)

    def choose_query(self, query_set, cost_fn, cert_ok):
        best, best_gain = None, -1e9
        for q in query_set:
            if not cert_ok(q):            # 扰动询问必须自带证书
                continue
            gain = (self.expected_info(q)
                    - cost_fn.cog(q) - cost_fn.anchor(q) - cost_fn.safe(q))
            if gain > best_gain:
                best, best_gain = q, gain
        return best, best_gain


# RES：共享证据 + 共识 + 分歧（鲁棒对数意见池）
class RequirementEvidenceSharing:
    def __init__(self, tau_need=0.2):
        self.tau_need = tau_need
        self.log = {}                      # robot_id -> accumulated log-likelihood

    def write(self, robot_id, loglik, weight=1.0):
        self.log[robot_id] = self.log.get(robot_id, 0.0) + weight * loglik

    def consensus(self):
        tot = sum(self.log.values())
        return softmax_loglik(tot)

    def divergence(self, Qs, Qbar):
        return max(kl(Q, Qbar) for Q in Qs)

    def split_alarm(self, Qs):
        Qbar = self.consensus()
        D = self.divergence(Qs, Qbar)
        return D > self.tau_need, D, Qbar


# QEC：询问节流器（最优询问率 + 锚定防护）
class QueryEffortController:
    def __init__(self, I_inf, N0, c_q, c_anchor, lambda_max):
        self.I_inf, self.N0 = I_inf, N0
        self.c_q, self.c_anchor = c_q, c_anchor
        self.lambda_max = lambda_max

    def optimal_budget(self):
        denom = (self.c_q + self.c_anchor) * self.N0
        if denom <= 0 or self.I_inf <= denom:
            return 0.0
        return self.N0 * math.log(self.I_inf / denom)

    def budget_left(self, used):
        return max(0.0, self.optimal_budget() - used)


# CCT：组合式团队证书
class ComposableTeamCertificate:
    def __init__(self, tau_need):
        self.tau_need = tau_need

    def validate(self, Js, Qbar, D_team, joint_a, comm_hash):
        if any(not J.valid_against(Qbar) for J in Js):
            return False, 'REFERENCE_MISMATCH'
        if D_team > self.tau_need:
            return False, 'NEED_SPLIT'
        for i in range(len(joint_a)):
            for j in range(i + 1, len(joint_a)):
                if margin_rr(joint_a[i], joint_a[j]) < 0:
                    return False, 'ROBOT_ROBOT'
            if margin_rh(joint_a[i]) < 0:
                return False, 'ROBOT_HUMAN'
        if not all_same(comm_hash):
            return False, 'COMM_INCONSISTENT'
        return True, 'OK'


# ROLE：需求不确定下的鲁棒角色分配
class RobustRoleAllocator:
    def __init__(self, eps):
        self.eps = eps

    def allocate(self, roles, Qbar):
        best, best_wc = None, -1e9
        for rho in roles:
            credal = kl_ball(Qbar, self.eps)
            worst = min(expected_utility(rho, th) for th in credal.samples())
            if worst > best_wc:
                best, best_wc = rho, worst
        return best


# DDA + NVA：漂移报警 + 需求审计（异步）
class DemandDriftAlarm:
    def __init__(self, h=3.0):
        self.h, self.S = h, 0.0

    def update(self, loglik_new, loglik_old):
        self.S = max(0.0, self.S + loglik_new - loglik_old)
        return self.S > self.h

def CONCERT_round(M, obs):
    V, T, P, L, P_cloud, W_meas, tactile, img, depth, flow = obs
    M.lsf.update_geometry(P_cloud)
    x_prime = M.lsf.fuse(M.usr.fuse(V, T, P, L))

    # 1) 需求更新与共识（语义流）
    ev = M.unc.observe(img, depth, flow, x_prime)
    M.unc.update(ev)
    split, D_team, Qbar = M.res.split_alarm([M.unc.Q] + M.team_Qs)

    # 2) 主动询问（受预算与证书约束）
    if split or M.qec.budget_left(M.q_used) > 0:

            M.res.write(M.id, M.unc.evidence_from(q, y))

    # 3) 团队联合世界模型滚动
    act_seq = M.vista.ach.propose_actions(x_prime, H=M.vista.H, steps=5)
    wm = M.jwm.rollout(x_prime, act_seq, teammates=M.team_obs, k=5)

    # 4) 组合证书 + 团队前缀
    Js = [M.cert.issue(x_prime, act_seq) for _ in M.team_ids]
    ok, why = M.cct.validate(Js, Qbar, D_team, act_seq, M.comm_hash)
    k_need = M.csc.need_horizon(Qbar, wm)
    k_role = M.csc.role_horizon(Qbar, M.roles)
    k_ras = M.csc_ras_wm.certified_prefix_ras_wm(
        act_seq, M.joint_post, M.m_ras, M.alpha_chunk, wm)
    k_star = min(k_ras, k_need, k_role, M.m_team) if ok else 0

    # 5) 需求层风险缩放
    lam_need = clamp(1 - 0.3*entropy(Qbar) - 0.5*D_team
                     - 0.2*(why == 'DRIFT'), 0.4, 1.0)
    lam = M.risk_scale(M.joint_post) * lam_need

    # 6) 安全执行
    tau_cmd = M.vista.pi_sigma.prefix_dispatch(act_seq[:k_star]) * lam
    tau_cmd = M.ers.shaping(tau_cmd, M.joint_post)

    # 7) 异步需求审计 + 漂移监测
    M.nva.submit_async(wm, {'Qbar': Qbar, 'need_stmt': render_need(Qbar)})
    if M.dda.update(M.unc.last_loglik(), M.unc.prev_loglik()):
        M.mark_drift()

    return k_star, lam, Qbar, D_team, why
```

## 3. 推导

**引理 13（最优询问率）** 设询问的信息增益为凹函数 `I(N) = I_∞(1 − e^{−N/N_0})`，单次询问的总成本 `c = c_cog + c_anchor`，净收益 `G(N) = I(N) − cN`。则 `G` 在 `N* = N_0 ln(I_∞/(c·N_0))` 处取最大值；当 `c·N_0 ≥ I_∞` 时 `N* = 0`（不询问最优）。`N > N*` 后每多问一次，净效用严格下降——**过度询问是负收益的**。

**引理 14（相关证据的有效样本量）** 若 `n` 台机器人的每条证据两两相关系数为 `ρ_c`，证据总量为 `nN`，则均值的方差为 `σ²(1 + (n−1)ρ_c)/(nN)`，等价独立样本量 `N_eff = nN / (1 + (n−1)ρ_c)`。当 `ρ_c = 1` 时 `N_eff = N`（与单机相同）；当 `ρ_c = 0` 时 `N_eff = nN`（线性增益）。由此，**增加机器人数量在共因误差下不提升需求辨识度**——这是共识失效的定量根源。

**引理 15（询问的非扰动安全性）** 若询问 `q` 属于非扰动类，且在执行时团队处于已认证安全集内，则询问期间联合裕度 `m_team(t) ≥ 0` 对所有 `t` 成立；且询问不改变 `J_team` 的几何前提。故非扰动询问不会降低安全性，只会消耗交互预算。

**定理 14（组合证书的失败界）** 在定义 273 的五个条件全部成立时，团队在视界 `k` 内的失败概率满足
`P_fail ≤ Σ_i α_i + Σ_{i<j} L_m·max(0, −m_ij) + n·L_q·D_team + α_comm`，
其中 `α_i` 为单机证书的失败率，`L_m, L_q` 为裕度与需求分歧对失败概率的 Lipschitz 常数，`α_comm` 为通信不一致导致的失败率。特别地，当 `D_team = 0` 且通信一致时，退化为经典单机可加界。**该界表明：需求分歧是一个与几何裕度同量级的失败源，不能当作"软约束"忽略。**

**定理 15（安全主动询问的遗憾界）** 在引理 13、15 下，若按 `q*` 选择非扰动询问并在 `N*` 次后停止，则相对"全知需求"的期望效用遗憾
`Regret(N*) ≤ Δ_0·(1 − β)^{N*} + ε_Q + c·N*`，
其中 `Δ_0` 为先验不确定性带来的最大效用差，`β` 为单次询问的信息收缩率，`ε_Q` 为量化/建模误差。当 `β` 有界且 `N*` 满足引理 13 时，`Regret` 随 `N*` 指数下降后被成本项接管——存在一个**不可消除的最优遗憾**。

**定理 16（需求可证伪性）** 若反事实探针按速率 `μ` 调度，且任一错误需求 `θ'` 与真实需求 `θ` 满足效用差 `ΔU > Δ_min`，则持续未检出错误需求的概率
`P(undetected at T) ≤ exp(−μ·T·f_need·p_flip) + P_falsepos`，
其中 `p_flip` 为探针诱导出可观测行为差异的概率。故 `f_need ≥ f_min` 是 CONCERT 证书有效性的必要条件（定义 281）。

**定理 17（需求漂移的检测延迟）** 对幅度为 `Δ_drift` 的阶跃漂移，CUSUM 的期望检测延迟 `E[τ_d] ≤ h/Δ_drift + O(1)`，误报率 `≤ e^{−h}`。取 `h = 3` 时，误报约 `5%`，对 `Δ_drift ≥ 1` 的漂移平均 `≤4` 个证据周期检出。

**定理 18（共识残差不可消除性）** 在定义 283 下，`lim_{t→∞} D_team(t) ≤ ε_comm`。若 `ε_comm > 0`，则不存在仅靠共识协议使 `Q̄` 收敛到真值 `δ(θ*)` 的保证；必须引入**与团队先验独立的证据通道**（用户直接确认、反事实探针、外部真值），否则共识只能收敛到"团队内部自洽"，而非"用户真实需求"。

## 6. 本轮最大风险

**一句话**：CONCERT 把「用户需求」建模为一个**平稳、低维、可由独立证据恢复的潜变量 θ**，但真实需求是被交互**建构**出来的、会漂移、且多台机器人的证据高度相关——于是共识协议会把「相关的错误」压平成「一致的确信」，团队可能以全部合法的证书、零安全违规、完美的共识，**安全且一致地执行一个错误的目标**，且现有任何一层证书都不会报警（这正是 VISTA→RAS→SimRAS 都未覆盖的盲区：**正确地做错的事**）。

**次级风险与缓解**：
1. **共识放大共因错误**：强制保留独立证据通道（用户直接确认、反事实探针、外部真值），并监控 `N_eff` 而非仅监控 `D_team`；
2. **询问锚定污染需求**：随机化问法顺序、使用中性表述、记录 `c_anchor`；把询问本身当作"可能改变需求"的干预而非被动测量；
3. **需求漂移漏检**：CUSUM 之外叠加 NVA 语义漂移检测（"用户最近的说法和之前矛盾吗"）；
4. **计算/通信开销**：`n` 增大时 CCT 的 `O(n²)` 与共识通信成为瓶颈 → 分层共识（簇内先聚、簇间再聚）；
5. **用户误报/策略性隐瞒**：把"用户可能不说真话"放入 `ℰ_need`，用行为-声明一致性做交叉验证，不一致时降 `λ_need` 而非直接信任声明。

J_team = (J_1..J_n, Q̄, D_team, L_shared_hash, ρ, comm_hash)
```
`J_team` 有效当且仅当：1) `∀i, J_i` 相对 `Q̄` 有效；2) `∀i<j, m_ij(a_i,a_j) ≥ 0`；3) `∀i, m_{i,h}(a_i) ≥ 0`；4) `D_team ≤ τ_need`；5) `comm_hash` 全队一致。

**定义 274（需求条件下的鲁棒角色分配）** `C_ε(Q̄) = {θ : KL(θ‖Q̄) ≤ ε}`，
```
ρ* = argmax_ρ min_{θ∈C_ε(Q̄)} E[U_θ | ρ],  s.t. ∀θ∈C_ε, C_θ 成立
```
当 `ΔU(ρ) = max_{θ∈C_ε}E[U_θ|ρ] − min_{θ∈C_ε}E[U_θ|ρ] > τ_role` 时，角色"需求敏感"，必须先澄清需求再分配。

**定义 275（需求漂移）** `S_t = max(0, S_{t−1} + log ℓ_t(θ̂_t) − log ℓ_t(θ̂_{t−1}))`。`S_t > h` 时触发 `H_need_drift`：重置共享日志、上调询问率、缩短 `k*`。

**定义 276（询问证书 / 询问前缀）** 询问 `q` **非扰动**当且仅当询问期间联合状态停留在已认证安全集内；**扰动询问**（需移动展示）必须携带认证前缀 `k_q`，且与主动作链接缝重叠 `o_q ≥ 0`。

**定义 277（需求可证伪探针）** 反事实探针是一对安全动作 `(a^+, a^-)`，使 `U_θ(a^+) > U_θ(a^-) ⇔ θ ∈ Θ_A`。执行并观测用户反应/后续行为，得到对 `Θ_A` 的判别证据。`f_need = P(∃探针使错误需求被拒)`。

**定义 278（多智能体联合世界模型 JWM）**
```
JWM_φ = (Enc, dyn_head, emo_head, fault_head, other_robot_head, human_need_head)
```
`other_robot_head` 预测队友动作/信念，`human_need_head` 输出 `θ` 后验演化。损失
```
L = L_recon + λ_e L_emo + λ_f L_fault + λ_o L_other + λ_n L_need + λ_c L_consensus
```
`L_consensus` 惩罚与 `L_shared` 不一致的独立幻觉。

**定义 279（需求审计员 NVA）** `NVA = (Render, VQA, PromptTpl, StructParser)`。对 JWM 渲染的团队滚动视频提出三类问题：需求满足性、反事实敏感性、理解一致性。输出 `NeedAudit = {satisfied, counterfactual_flips[], divergence_flags[], need_adjust}`。

**定义 280（AIC-MC 干扰与共因）**
```
ℰ_MC = ℰ_SimRAS × ℰ_need × ℰ_consensus × ℰ_evidence
```
`ℰ_need = {需求欠定, 需求漂移, 询问锚定, 用户误报}`，`ℰ_consensus = {通信延迟/丢包, 拜占庭机器人, 权重坍缩}`，`ℰ_evidence = {证据相关, 共享盲点, 数据集偏置}`；共因 `ℰ_common_need`（同一训练分布使全队共享同一错误先验）。

**定义 281（J_CONCERT 证书）**
```
J_CONCERT = (J_SimRAS, need_hash, need_posterior_digest, need_divergence,
             consensus_ver, role_assign_hash, query_budget_used, falsify_rate, drift_flag)
```
`Valid ⇔ Valid(J_SimRAS) ∧ D_team ≤ τ_need ∧ f_need ≥ f_min ∧ (drift_flag = False ∨ 已重认证)`。

**定义 282（团队认证前缀）** `k*CONCERT = min(k_VISTA, k_emo, k_wm, k_need, k_role, m_team)`，`k_need` 为需求后验保持 `D_team ≤ τ_need` 的步数，`k_role` 为 `ρ*` 不变的步数。

**定义 283（共识收敛条件）** 设各证据似然的对数凹性常数 `L_i`、通信拓扑代数连通度 `λ_2`。若每轮交换充分统计量且 `λ_2 > 0`，则
```
D_team(t) ≤ D_team(0)·exp(−λ_2 t / L_max) + ε_comm
```
残差下界 `ε_comm` 意味着**共识永远不会自动变成正确**。

**定义 284（需求层风险缩放）**
```
λ_need = 1 − α_n·H(Q̄) − β_n·D_team − γ_n·1[drift_flag] ∈ [0.4, 1.0]
λ = λ_risk · λ_need
```

**定义 285（在线部署不变式）** 实时流只做：需求后验查表、`D_team ≤ τ_need` 布尔判定、`k*CONCERT` 截断、`λ_need` 乘法、安全回退。后验更新、共识轮、询问选择、组合证书、需求审计在语义流/后台；离线标定 `τ_need, α_n, β_n, h, f_min` 与 JWM 预训练。

# IP-243 UNC：需求制图器
class UserNeedCartographer:
    def __init__(self, theta_space, tau_need=0.2):
        self.Theta, self.tau_need = theta_space, tau_need
        self.Q = theta_space.uniform_prior()

    def observe(self, img, depth, flow, x):
        return [behavior_evidence(img, depth, flow, x),
                context_evidence(x)]

    def update(self, evidence):
        for e in evidence:
            self.Q = normalize(self.Q * e.likelihood(self.Theta))
        return self.Q

    def expected_info(self, q):
        return entropy(self.Q) - expected_entropy_after(self.Q, q)

    def choose_query(self, query_set, costs, cert_ok):
        best, best_gain = None, -1e9
        for q in query_set:
            if not cert_ok(q):
                continue
            gain = (self.expected_info(q)
                    - costs.cog(q) - costs.anchor(q) - costs.safe(q))
            if gain > best_gain:
                best, best_gain = q, gain
        return best, best_gain

    def need_statement(self):
        return render_need(self.Q)


# IP-244 RES：共享证据 + 共识 + 分歧
class RequirementEvidenceSharing:
    def __init__(self, tau_need=0.2):
        self.tau_need, self.log = tau_need, {}

    def write(self, robot_id, loglik, weight=1.0):
        self.log[robot_id] = self.log.get(robot_id, 0.0) + weight * loglik

    def consensus(self):
        return softmax_loglik(sum(self.log.values()))

    def divergence(self, Qs, Qbar):
        return max(kl(Q, Qbar) for Q in Qs)

    def split_alarm(self, Qs):
        Qbar = self.consensus()
        D = self.divergence(Qs, Qbar)
        return D > self.tau_need, D, Qbar

    def robust_weight(self, robot_id, reliability):
        # 拜占庭检测：偏离共识过远的证据降权
        return clamp(reliability, 0.0, 1.0)


# IP-245 QEC：询问节流器（最优预算 + 锚定防护）
class QueryEffortController:
    def __init__(self, I_inf, N0, c_q, c_anchor, lambda_max=3.0):
        self.I_inf, self.N0 = I_inf, N0
        self.c_q, self.c_anchor = c_q, c_anchor
        self.lambda_max = lambda_max

    def optimal_budget(self):
        denom = (self.c_q + self.c_anchor) * self.N0
        if denom <= 0 or self.I_inf <= denom:
            return 0.0
        return min(self.lambda_max, self.N0 * math.log(self.I_inf / denom))

    def budget_left(self, used):
        return max(0.0, self.optimal_budget() - used)


# IP-246 CCT：组合式团队证书
class ComposableTeamCertificate:
    def __init__(self, tau_need):
        self.tau_need = tau_need

    def validate(self, Js, Qbar, D_team, joint_a, comm_hash):
        if any(not J.valid_against(Qbar) for J in Js):
            return False, 'REFERENCE_MISMATCH'
        if D_team > self.tau_need:
            return False, 'NEED_SPLIT'
        for i in range(len(joint_a)):
            for j in range(i + 1, len(joint_a)):
                if margin_rr(joint_a[i], joint_a[j]) < 0:
                    return False, 'ROBOT_ROBOT'
            if margin_rh(joint_a[i]) < 0:
                return False, 'ROBOT_HUMAN'
        if not all_same(comm_hash):
            return False, 'COMM_INCONSISTENT'
        return True, 'OK'


# IP-247 ROLE：鲁棒角色分配
class RobustRoleAllocator:
    def __init__(self, eps=0.3, tau_role=0.2):
        self.eps, self.tau_role = eps, tau_role

    def allocate(self, roles, Qbar):
        best, best_wc = None, -1e9
        for rho in roles:
            samples = kl_ball_samples(Qbar, self.eps)
            worst = min(expected_utility(rho, th) for th in samples)
            if worst > best_wc:
                best, best_wc = rho, worst
        return best

    def sensitive(self, rho, Qbar):
        samples = kl_ball_samples(Qbar, self.eps)
        vals = [expected_utility(rho, th) for th in samples]
        return max(vals) - min(vals) > self.tau_role


# IP-248 DDA：需求漂移报警
class DemandDriftAlarm:
    def __init__(self, h=3.0):
        self.h, self.S = h, 0.0

    def update(self, loglik_new, loglik_old):
        self.S = max(0.0, self.S + loglik_new - loglik_old)

# IP-249 NVA + IP-250 JWM：需求审计与联合世界模型
class JointWorldModel:

        return preds

def CONCERT_round(M, obs):
    V, T, P, L, P_cloud, W_meas, tactile, img, depth, flow = obs
    M.lsf.update_geometry(P_cloud)

## 4. 推导

**引理 13（最优询问率）** 设 `I(N) = I_∞(1 − e^{−N/N_0})` 为凹信息增益，单次总成本 `c = c_cog + c_anchor`，净收益 `G(N) = I(N) − cN`。由 `G'(N) = (I_∞/N_0)e^{−N/N_0} − c = 0` 得 `N* = N_0 ln(I_∞/(cN_0))`。当 `cN_0 ≥ I_∞` 时 `N*=0`。`G''<0` 保证 `N*` 为全局最大；`N>N*` 后净效用严格递减。

**引理 14（相关证据的有效样本量）** `n` 台机器人证据两两相关 `ρ_c`、总量 `nN`，则均值方差 `σ²(1+(n−1)ρ_c)/(nN)`，故 `N_eff = nN/(1+(n−1)ρ_c)`。`ρ_c→1 ⇒ N_eff→N`；`ρ_c→0 ⇒ N_eff→nN`。**增加机器人数量在共因误差下不提升需求辨识度。**

**引理 15（非扰动询问的安全性）** 非扰动询问期间联合状态停留在已认证安全集内，故 `m_team(t) ≥ 0, ∀t`，且不改变 `J_team` 的几何前提。非扰动询问只消耗交互预算，不降低安全性。

**定理 14（组合证书失败界）** 在定义 273 的五条件成立时，
```
P_fail ≤ Σ_i α_i + Σ_{i<j} L_m·max(0, −m_ij) + n·L_q·D_team + α_comm
```
当 `D_team = 0` 且通信一致时退化为经典单机可加界。**需求分歧与几何裕度同量级，不可当软约束忽略。**

**定理 15（安全主动询问的遗憾界）** 在引理 13、15 下，按 `q*` 选择非扰动询问并在 `N*` 次后停止，则
```
Regret(N*) ≤ Δ_0·(1−β)^{N*} + ε_Q + c·N*
```
`Δ_0` 为先验不确定性带来的最大效用差，`β` 为单次信息收缩率，`ε_Q` 为量化误差。存在不可消除的最优遗憾 `c·N*`。

**定理 16（需求可证伪性）** 反事实探针按速率 `μ` 调度，任一错误需求 `θ'` 与 `θ` 的效用差 `ΔU > Δ_min`，则持续未检出概率
```
P(undetected at T) ≤ exp(−μ·T·f_need·p_flip) + P_falsepos
```
故 `f_need ≥ f_min` 是 `J_CONCERT` 有效的必要条件。

**定理 17（需求漂移检测延迟）** 对幅度 `Δ_drift` 的阶跃漂移，CUSUM 期望检测延迟 `E[τ_d] ≤ h/Δ_drift + O(1)`，误报率 `≤ e^{−h}`。`h=3` 时误报约 `5%`，`Δ_drift≥1` 时平均 `≤4` 个证据周期检出。

**定理 18（共识残差不可消除性）** 定义 283 下 `lim_{t→∞} D_team(t) ≤ ε_comm`。若 `ε_comm > 0`，仅靠共识协议不能保证 `Q̄ → δ(θ*)`；必须引入与团队先验独立的证据通道（用户直接确认、反事实探针、外部真值），否则共识只收敛到"团队内部自洽"而非"用户真实需求"。

| E272 | 实测 `P_fail` 随 `D_team` 近似线性上升 | 定理 14（分歧=失败源） |
| E275 | `f_need` 随 `Δ_min` 增大而上升，存在 `f_need` 平台 | 定理 16（可证伪性） |
| E280 | 无独立探针时错误持续率 > 50%；有探针后 < 10% | 定理 18（共识≠正确） |

## 8. 本轮最大风险

**一句话**：CONCERT 把「用户需求」建模为**平稳、低维、可由独立证据恢复的潜变量 θ**，但真实需求是被交互**建构**出来的、会漂移、且多台机器人的证据高度相关——共识协议会把相关的错误压平成一致的确信，团队可能以全部合法的证书、零安全违规、完美的共识，**安全且一致地执行一个错误的目标**，而 VISTA/RAS/SimRAS 的任何一层证书都不会报警（核心盲区：**正确地做错的事**）。

**次级风险与缓解**：
1. **共识放大共因错误**：强制保留独立证据通道（用户确认、反事实探针、外部真值），并监控 `N_eff` 而非只看 `D_team`；
2. **询问锚定污染需求**：随机化问法顺序、中性表述、记录 `c_anchor`，把询问视为干预而非被动测量；
3. **需求漂移漏检**：CUSUM 叠加 NVA 语义漂移检测（"最近的说法和之前矛盾吗"）；
4. **通信/计算开销**：`n` 增大时 CCT `O(n²)` 与共识通信成为瓶颈 → 分层共识（簇内先聚、簇间再聚）；
5. **用户误报/策略性隐瞒**：把"用户可能不说真话"纳入 `ℰ_need`，用行为-声明一致性交叉验证，不一致时降 `λ_need` 而非信任声明。
