# 第 8 轮（灵感循环第 3 轮） · CARE：力觉是接口的盲区，ROS2 是离线靶场，伦理审查是让行控制器

> 检索/复核日期：2026-10-26（UTC）。赛事身份先确认：用户所指仍是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。没有发现第二个更匹配的 UniBot。
>
> 本轮三个灵感词是「力觉传感」「ROS2」「伦理审查」。我一开始觉得它们分属硬件、中间件、合规三个世界，查完事实后改变了判断：**它们其实是同一件事的三个面——评测刻意不暴露的"接触层"**。力觉传感暴露的是观测缺口；ROS2 暴露的是评测接口与本地开发环境的错位；伦理审查暴露的是 human 轴的安全/让行语义。三者合起来，指向一个模型无关的接触反应 wrapper：**CARE（Contact-Aware Reversible Execution）**。
>
> 与上一轮（第 7 轮 PILOT）的关系：上一轮的"终局放置是闸门"判断保留，但**排名公式必须修正**——官方按总平均成功率排序，步骤分只在成功率相同时做 tie-break。上一轮把"步骤分"当第二主轴的预算算术作废；SSG 从"步骤分优化器"降为"成功门控 + 失败诊断"。这一轮的火力从"放置"扩展到"接触 + 让行"，因为它们是成功率主排序下更大的共同瓶颈。

## 0. 本轮先核实：八个新事实/修正

### 0.1 排名公式：成功率是主排序，步骤分只是 tie-break

官方手册（[S1]）写得很清楚：32 个任务各算成功率，取总平均成功率排名；总成功率相同，才看总平均步骤分；再相同，提交更早者靠前。这个修正很关键：

- 上一轮把"成功率 + 步骤分"当成两个并列的优化目标，甚至算了步骤分的期望收益；这在排名上不成立。
- 步骤分仍有价值：它是 tie-break，也是最好的**步骤级诊断信号**（钱丢在哪一步）；但它不是主目标。
- 因此本轮的评估一律以**成功率**为主，步骤分只用于诊断和同分比较。

### 0.2 每任务 10 次：5 个泛化类型 × 2 次，共 320 trials

手册（[S1]）的评测协议：每个任务跑 10 次独立实验；5 个泛化类型（位置、干扰物、背景、未见物品、人为干扰）各 2 次；单次最长 180s。折算下来：

- 32 × 10 = **320 trials**；每个轴 32 × 2 = **64 trials**。
- **human 轴占 20%**（64/320）。这是 CARE-YR 的直接杠杆。
- 180s 对长程任务（zip、stack、unplug）很紧；CARE 的探测/让行必须有预算守卫。

### 0.3 力觉：API 和数据都没有，硬件有但不可用

这是本轮最重要的"负事实"：

- 提交模板 README（[S6]）的观测只有 4×RGB 480×640、双臂关节/EE 位姿、夹爪开度、下半身、语言字符串；动作只有关节或 EE 目标 + 夹爪命令。**没有 force/torque/tactile 通道。**
- 官方数据集（[S7][S8]）的 features 同样没有力/力矩/触觉；`action.gripper_controls` 是 4 维，实测形如 `[10, 0, 10, 0]`，更像目标/速度而不是力。
- 硬件侧：G1 可选 Dex3-1 力控三指手，官方页面明确写了 **33 个触觉传感器**、力位混合控制（[S11]）；Dex1-1 平行夹爪有 **5–120N 可调抓握力**、50–375mm/s、90mm 行程（[S10]）。但挑战数据用的是 Dex1 系列，评测机器人不是我们的，**不能加装传感器**；API 也不暴露夹爪力/关节力矩。
- 结论：力觉不是"买个传感器"的问题，而是**可观测性**问题。我们只能从位置/开度/图像里"推断"接触。

### 0.4 榜单仍是 Coming Soon，"榜首 <30%"不能当官方事实

截至 2026-10-26（UTC），`leaderboard.html` 和 `runs.html` 仍是占位（[S3][S4]）；`leaderboard_data.json` 被反爬返回 HTML；详情页出现 GigaBrain-0 / DM0 等名字，但没有真实指标。上一轮看到的"8 个模型、榜首约 29.7%"是占位脚本的产物，不是官方实时榜。

所以我在文中会把"<30%"写成**设计假设/社区先验**，不写成官方事实。即使真实榜首高于 30%，8 个 Hard 任务 + 20% human trials 仍然把接触/让行推到头号瓶颈的位置。

### 0.5 数据集：32 个 repo、约 33k episodes、169h，但没有力

HF collection（[S7]）现在有 32 个数据集，约 33k episodes / 169h / 811GB；HangCup 1,043 条 / 194,564 帧 / 30fps，lastModified 2026-10-14（[S8]）。四路相机、EE 位姿在 base 与 torso 两套坐标里都有。数据量足够做行为克隆/少样本，但**没有一条力标签**。这意味着：

- 力感知只能走"仿真特权标签 + sim-real 蒸馏"或"本体感知探测"，不能直接监督。
- 官方数据的价值在视觉/动作先验，不在接触物理。

### 0.6 WLA-1.0-Base 已全量开源，且开源计划包含挑战数据集

WLA-1.0-Base 2026-09-28 发布（[S22]）：6B、Apache-2.0、约 2,500 小时真机数据、64 个任务、支持两指夹爪和五指手；GitHub 有 fine-tune 与 LoRA 代码，且开源计划里明确列了 `unibot-v1-challenge-dataset`。这是域匹配最好的底座。另有 GigaBrain-0.7（3.5B、37,000+ 小时、三系统架构，[S23]）和 DM0（2B、RoboChallenge Table30 generalist 37.3%，[S24]）可选。底座不是本轮的研究贡献，但选型会影响延迟和接触反应速度。

### 0.7 README 第 6 节：延迟、动作规律性、结果可信度会被记录

提交模板 README（[S6]）新增：评测会记录策略的**延迟**和**动作规律性**，可能展示；结果可信度也可能被评估。这是一个隐藏的工程评分维度：

- 延迟高/抖动大，会被看见；动作跳变/NaN/越界，会被看见。
- 这直接支持 LDS（Latency-Deterministic Serving）和 action regularity guard，而不是"能跑就行"。
- 也意味着"用 ROS2 包一层"如果加在关键路径上，是负资产。

### 0.8 官方数据的 EE 残差是"滞后传感器"，不是"力传感器"

我最初的想法很自然：`action` 是目标位姿，`observation.state` 是实际位姿，二者之差就是跟踪误差；接触时跟踪误差会变大，所以残差可以当力代理。为了验证，我用 HF datasets-server 的 rows API 抓了 PlugCharger / HangCup / StackBowls 各几百帧，算了 EE 位置残差和相邻帧 EE 速度的相关系数：

- PlugCharger：残差均值 13–15mm，p90 19–24mm，max 37mm；corr(vel, res) = 0.33 / 0.36（左右臂；有一条右臂 -0.21）。
- HangCup：残差均值 15–19mm，p90 26–29mm，max 70mm；corr = 0.54–0.90。
- StackBowls：残差均值 13mm，max 49mm；corr = 0.63–0.80。

结论：**原始残差主要是速度/跟踪滞后，不是接触力。** 这是一个很有价值的负结果——它否定了"残差=力"的 naive 方案，逼出了本轮的核心设计：准静态差分探测。它也解释了为什么直接拿残差做接触检测会在快速运动段大量误报。

## 1. 三个灵感词，三次纠偏

### 1.1 力觉传感：不是传感器问题，是可观测性问题

我把"加力觉"拆成三条路线：

1. **硬件路线**：Dex3-1 触觉阵列 / Dex1-1 力矩反馈 / 腕部六维力。事实是评测机器人不是我们的，不能加装；API 也不读这些通道。这条路直接封死。
2. **蒸馏路线**：用仿真/实验室的力标签训练一个 force head，推理时从视觉/本体感知蒸馏出力。FD-VLA（[S14]）就是这么做的：Force Distillation Module 把可学习 query token 映射到真实力信号的 latent；HapticVLA（[S15]）更进一步，训练时用触觉、推理时不用。这条路可行，但需要**特权力标签**；官方数据没有，只能从仿真拿，存在 sim-real gap。
3. **本体感知路线**：从位置/开度/动作历史推断接触。原始残差被速度污染（0.8 的实测），但**准静态差分**可以消掉速度项：先保持 100ms 测基线残差，再发 2mm 小步、保持 100ms 测稳态残差；两者之差主要是接触/重力变化，不是滞后。再加上夹爪 stall（命令闭合但开度停住）这个几乎免费的接触/抓取信号，就能在**不训练大模型**的情况下得到接触概率。

我的选择是 **2 + 3 的组合**：仿真力标签训练一个小的 Contact Observer（CWM-lite / force head），推理时用准静态探测和夹爪 stall 做校准与兜底。硬件路线不做。

这也解释了为什么本轮不直接做"force-aware VLA"：ForceVLA2（[S13]）、TaF-VLA（[S21]）、TAO-Force（[S16]）、Opt2VLA（[S17]）、FM-VLA（[S18]）、CR-VLA-Force（[S19]）都需要力/触觉输入或训练标签；TacCoRL（[S20]）用仿真触觉做 sim-real co-training，方向对，但仍是"把触觉当输入"。我们的差异是：**把接触当成一个可主动探测的事件，而不是一个被动的输入通道**。这是"传感器缺失"下的另一种解法。

### 1.2 ROS2：不是评测接口，是离线靶场

我一开始想：既然机器人是 ROS2 生态，能不能用 ROS2 做策略服务？查了提交模板（[S6]），评测是 WebSocket/msgpack 的 `get_action(obs)`，不是 ROS2 topic/service。把 ROS2 放在 `get_action` 的关键路径上，只会增加序列化/调度/发现延迟，而且评测端根本不需要。

所以我把它降级为**离线靶场**，只做四件事：

1. **rosbag2 回放**：把调试槽/本地采集的观测-动作-延迟录下来，离线重放同一策略或新策略，做反事实比较（[S26]）。
2. **lifecycle N 端口编排**：用 managed node 的 configure/activate/deactivate 管理 N 个评测端口的生命周期，做健康检查、状态隔离、故障重启（[S27]）。
3. **contact monitor / safety guard**：把 Contact Observer、Human Detector、Yield Manager 作为独立节点，方便可视化、录制、红队测试。
4. **A/B 与延迟测量**：同一段 bag，跑 baseline 和 CARE，比较成功率/延迟/动作规律性。

关键纪律：**ROS2 不进 policy 的 `get_action`**。它是研究工具，不是提交物。这样既保留了 ROS2 的工程价值，又不把延迟风险带进评测。

### 1.3 伦理审查：不是评分项，是让行控制器

伦理审查在竞赛里通常不是打分项，但它和 human 轴直接相关：human 轴占 20% 的 trials，官方备注里明确有"把物体移走""把拉链拉开""把盖子拧回去"这类 undo 剧本（上一轮已抓取，[S2]）。如果策略在人类靠近时继续推/抓，既不安全，也几乎一定失败。

所以我把伦理审查翻译成三个可执行的东西：

1. **安全包络**：G1 约 35kg、膝关节最大 120N·m（[S12]）；在人附近限制 EE 速度、夹爪力、探测幅度；不接触人脸/头部；human 进入工作区就减速/停止。
2. **CARE-YR（Yield & Resume）**：停止 → 松开夹爪 → 沿来路后退 → 保持 → 等人离开 → 重定位 → 判断是否被 undo → 回退 SSG 步骤 → 恢复。这不是"礼貌"，是 human 轴的成功率策略。
3. **数据/评测诚信**：官方数据 Apache-2.0，可以用；L2L 自采数据需要 IRB/知情同意，默认 DEFER；不做 task-ID 硬编码、不读评测器状态、不利用时间/随机种子漏洞；所有输入输出留痕，供审计。

伦理审查因此不是"写一份文档"，而是**一个让行控制器 + 一份可审计的安全案**。这也是本轮相对上一轮 NRB 的升级：从"恢复库"升级为"让行-回退-恢复"的闭环。

## 2. 主判断：CARE（Contact-Aware Reversible Execution）

### 2.1 为什么接触层是隐藏瓶颈

把事实摊开：

- 排名只看成功率；32 个任务里 8 个 Hard，接触密集任务遍布各难度（插排/插网线/拔线/拉拉链/拧盖/叠碗/挂杯等）。
- 每个任务的终局都是"成功闸门"；终局失败=整任务失败。上一轮已经证明终局放置是 32/32 的闸门。
- human 轴 20% 的 trials，官方备注就是 move/undo；不会让行/恢复，human 轴会大量丢分。
- 头部模型（GigaBrain-0.7、DM0、WLA）的语义/视觉泛化已经很强，公开失败案例集中在**最后 1–3cm 的接触、拔出、释放、被人打断**。这不是"再看多一点数据"能解决的，是**观测/控制接口**的问题。

所以 CARE 的定位不是"又一个 VLA"，而是**VLA 外面的接触反应层**：VLA 负责语义/粗操作，CARE 负责接触/让行/验证。模型无关，可以直接套 WLA、DM0 或 GigaBrain。

### 2.2 失败模型：接触任务的五种死法

1. **对不准**：插头/网线/拉链头/盖子没对齐，推不动或推歪。
2. **插不进/拔不出**：对准了但深度不够/角度不对/卡住；位置控制继续推，越推越糟。
3. **滑移/掉件**：夹爪闭合了但物体滑了；开度/视觉能看出来，但策略没有闭环。
4. **释放失败**：放下的瞬间弹跳/滚动/没到位；"放完就走"导致终局失败。
5. **被人打断**：人把物体移走/undo；策略继续按旧计划执行，或者撞到人。

CARE 的五件套一一对应：Contact Observer（1/2/3）、Probe Controller（2）、CARE-SVL（4）、CARE-YR（5）、SSG（全局门控/诊断）。

### 2.3 CARE 的五件套

- **Contact Observer**：夹爪 stall + 准静态差分残差 + CWM-lite（状态-动作动力学集成）+ 腕部视觉进度 + 人手检测。输出 contact/slip/grasp/human/progress。
- **Probe Controller**：把"位置控制"变成"准力控"——2mm 小步、100ms 保持、测稳态差分；插不进就螺旋搜索，拔不出就沿轴拉，拧不动就反向回位再拧，拉链卡住就轻抖再拉。所有探测有幅度/时长/次数上限。
- **CARE-SVL**：释放后等 0.5s，检查物体稳定性/位姿；不稳定就 nudge/regrasp；预算是 1–2 次。
- **CARE-YR**：人进入工作区/物体被移动/出现非预期接触 → 停止、松开、后退、保持、重定位、判断 undo、回退 SSG、恢复。
- **SSG**：官方评分步骤图，用作成功门控和诊断；不再用于步骤分优化。

### 2.4 关键洞察：准静态差分把"滞后"从"接触"里分离出来

原始残差 `r = a - s` 里混着控制器滞后、重力、摩擦、接触。速度相关 0.33–0.90，说明滞后是主项。准静态差分做两件事：

1. **时间上**：每个探测点保持 100ms，让控制器收敛；取后 50ms 的均值，消掉瞬态。
2. **空间上**：比较"探测前"和"探测后"的稳态残差，而不是绝对残差；重力/慢漂移被差分抵消。

如果 EE 实际位移远小于命令位移，且稳态残差变化大，就是** blocked/contact**；如果 EE 实际位移接近命令位移，残差变化小，就是 free。这个判据不依赖力传感器，也不依赖精确的控制器模型。它还可以估计**相对刚度**：`k ≈ Δr / Δp`，用于区分硬表面/软物体/卡住。

这就是"力觉传感"在本轮的真实落点：不是测力，而是**测"推不动"**。对于插排/网线/拉链/拧盖，这已经够了。

### 2.5 为什么这是研究贡献，不是工程活

- 它提出了一个**新的观测接口**：在无力/触觉通道的 API 下，用主动准静态探测把接触变成可观测事件；并给出了可证伪的判据（AUROC、稳态差分、刚度估计）。
- 它把**human 轴**从"鲁棒性问题"变成"可逆执行问题"：yield → rollback → resume，直接对应官方 undo 剧本。
- 它把**ROS2/伦理**从"合规成本"变成"离线靶场 + 安全案"，不占用评测关键路径。
- 它是**模型无关**的：不改 VLA 架构，不需要 force labels 在官方数据里，不需要评测机器人改装；单模型审计友好（大模型只有一个，接触 observer 很小/可关）。
- 它有**明确的失败条件**：如果准静态探测的接触 AUROC <0.7，或者 human 轴提升 <5pp，就回退到 SSG+SVL，不硬推。

## 3. 与第 7 轮的关系：保留、升级、降级、砍

### 3.1 保留

- **SSG 评分步骤图**：保留为成功门控 + 诊断；不再算步骤分收益。
- **PGL 放置目标阶梯 + 锚点渲染**：保留；终局放置仍是 32/32 闸门。
- **OPT 少样本放置位姿迁移**：保留，但简化；接触任务里用它做最终位姿。
- **DebugLoop**：保留；调试槽是本轮接触/human 验证的唯一真机回路。
- **WLA-1.0-Base**：保留为默认底座；域匹配最好，Apache-2.0，LoRA 可微调。
- **TLE/ACP/GF 数据引擎**：保留，但本轮只服务接触/让行场景，不铺全 32 任务。
- **AH-TP / Endurance Governor / Compliance Compiler**：保留为时长/预算/合规守卫。

### 3.2 升级

- **SVL → CARE-SVL**：从"落点 settle-verify"升级为"接触感知的释放/稳定性验证"；加入 contact observer 的稳态判据。
- **NRB → CARE-YR**：从"官方备注恢复库"升级为"让行-回退-恢复"闭环；加入 human detector、retreat、undo 检测。
- **PGL/OPT → contact-aware placement**：最终放置时用准静态探测确认"到底了/卡住了/没放稳"。

### 3.3 降级

- **ICR 检索**：延迟/复杂度高，且与接触层正交；降为 secondary，只有在离线诊断显示"语义/相位错误"时才启用。
- **L2L 产学研数据农场**：外部数据政策未确认 + IRB/同意成本；默认 DEFER，不进入本轮主路径。
- **TCLB**：降为离线比较台，不做模型选择。
- **FLEET**：保留为工程检查单，不再当"第六轴"。

### 3.4 砍

- **步骤分优化**：排名只看成功率；步骤分只做 tie-break/诊断。
- **全 32 任务高保真孪生**：成本高，收益低；只用接触任务的局部仿真。
- **自由仿真数据**：不做大规模 sim RL；只用仿真力标签训练 contact observer。
- **每任务 LoRA/模型合并**：单模型审计不友好；一个底座 + 一个 wrapper。

## 5. 可证伪预测与 Go/No-Go

我给自己定了四条可证伪的预测；做不到就回退，不硬讲故事。

1. **接触检测**：在仿真（有力标签）里，准静态差分 + CWM-lite 的接触 AUROC ≥0.80；原始瞬时残差的 AUROC ≤0.65。若准静态 <0.70，放弃 PCP 主路径，只用夹爪 stall + SVL。
2. **夹爪 stall**：在官方数据里，夹爪 stall 对"抓住/挡住"的检出率 ≥90%，误报 ≤10%（用视觉/相位弱标签校准）。若达不到，退回纯视觉进度。
3. **human 轴**：CARE-YR 在脚本化 human 干扰（move/undo/occlude）上，比 baseline +10pp 以上；折算到总成功率 +2pp 以上。若 <5pp，降级为"只做安全停止"，不做恢复。
4. **延迟**：LDS 在 N 端口并发下 p99 <100ms、动作异常率 <0.1%；若 p99 >150ms，换 DM0 2B 或减 chunk。

**Go/No-Go**：E4（准静态探测）AUROC ≥0.80 + E6（CARE-YR）human +10pp + E7 p99 <100ms，才允许进计分跑；否则回退到"SSG + PGL/OPT + CARE-SVL"的保守版。

## 6. 评分算术：为什么是 +3–5pp，不是 +10pp

320 trials、baseline p≈0.3 时，SE≈2.56pp；+3pp 约 1.2 SE，+5pp 约 2 SE。也就是说，**只有 +5pp 左右才可能在统计上站得住**。保守拆解：

| 杠杆 | trials 占比 | 假设提升 | 折算总提升 |
|---|---:|---:|---:|
| human 轴（CARE-YR） | 20% | +10pp | +2.0pp |
| 接触任务（PCP/ACP-2/SVL） | 37.5%（12/32） | +8pp | +3.0pp |
| 终局放置（PGL/OPT/SVL） | 100% | +2pp | +2.0pp |
| 重叠/保守折扣 | — | — | −2.0 至 −4.0pp |
| **合计（保守）** | | | **+3–5pp** |

这里的 12/32 是 8 Hard + 4 个接触密集 Medium 的粗估；human 轴与接触任务有重叠，所以打了折扣。目标不是"+10pp 的神话"，而是**在假设 baseline ~27% 时到 ~31–33%**，在 <30% 的假设榜上足够改变排位。如果真实榜首远高于 30%，这个增量仍然是对的方向，只是不够翻盘——那时需要底座/数据层面的提升，CARE 是必要不充分。

### 1.2 排名公式（本轮关键修正）

1. 32 个任务各算成功率，取**总平均成功率**排名；
2. 总成功率相同，按**总平均步骤得分**排名；

- 成功率是唯一主排序；步骤分只在同分时起作用。

## 2. 评分算术：从"综合分"改为"成功率主排序"

### 2.1 定义

- 任务 \(i\) 的成功率 \(p_i = \frac{1}{10}\sum_{r=1}^{10} \mathbf{1}[\text{success}_{i,r}]\)。
- 总成功率 \(P = \frac{1}{32}\sum_{i=1}^{32} p_i\)。
- 总步骤分 \(S = \frac{1}{32}\sum_{i=1}^{32} s_i\)，只在 \(P\) 相同时使用。
- 因此优化目标是 \(\max P\)，不是 \(\max (P + \lambda S)\)。

### 2.2 统计噪声

320 trials；二项标准误 \(SE = \sqrt{p(1-p)/320}\)：

| baseline p | SE | +3pp 的 z | +5pp 的 z |
|---:|---:|---:|---:|
| 0.20 | 2.24pp | 1.34 | 2.23 |
| 0.30 | 2.56pp | 1.17 | 1.95 |
| 0.40 | 2.74pp | 1.09 | 1.82 |

含义：+3pp 在 320 trials 下通常不显著；**+5pp 才接近 2 SE**。所以本轮目标定在 +3–5pp，且用配对种子/bootstrap 降噪；调试槽只做定性验证，不做显著性宣称。

### 2.3 杠杆敏感性（保守假设）

| 杠杆 | trials 占比 | 假设提升 | 折算总提升 | 说明 |
|---|---:|---:|---:|---|
| human 轴（CARE-YR） | 20%（64/320） | +10pp | +2.0pp | move/undo/occlude 剧本 |
| 接触任务（PCP/ACP-2/SVL） | 37.5%（12/32） | +8pp | +3.0pp | 8 Hard + 4 接触密集 Medium |
| 终局放置（PGL/OPT/SVL） | 100% | +2pp | +2.0pp | 与接触任务重叠 |
| 重叠/保守折扣 | — | — | −2.0 至 −4.0pp | human 与接触任务有交集 |
| **合计** | | | **+3–5pp** | 假设 baseline ~27% → ~31–33% |

### 2.4 结论

- 优先投 human 轴和接触任务；它们是成功率主排序下最大的共同瓶颈。
- 终局放置仍是 32/32 的闸门，但只做"够用"的 PGL/OPT/SVL，不再为步骤分做额外优化。
- 步骤分只用于诊断和同分；不再进入目标函数。

## 3. 官方数据的接触信号实证：负结果 + 弱正结果

### 3.1 方法

- 数据：HF datasets-server rows API，PlugCharger / HangCup / StackBowls 各抓 600–700 行（约 1–4 个 episode；受 429 限流，样本不大）。
- 残差：`r_t = || action.<side>_ee_pose_gripper_base[:3] - observation.state.<side>_ee_pose_gripper_base[:3] ||`。
- 速度：相邻帧 EE 位置差 × 30fps。
- 夹爪 stall：`action.<side>_gripper` 与 `observation.state.<side>_gripper` 的差，以及开度变化。
- 相关：Pearson corr(速度, 残差)。

### 3.2 结果

| 数据集 | 臂 | 残差均值 | p90 | max | corr(vel, res) |
|---|---|---:|---:|---:|---:|
| PlugCharger | left | 13.2mm | 19mm | 37mm | 0.35 |
| PlugCharger | right | 15.0mm | 24mm | 37mm | 0.33（ep1 −0.21） |
| HangCup | left | 14.3–15.6mm | 26mm | 69mm | 0.79–0.90 |
| HangCup | right | 17.8–20.2mm | 29mm | 70mm | 0.54–0.85 |
| StackBowls | left | 13.7mm | — | 49mm | 0.71–0.80 |
| StackBowls | right | 13.3mm | — | 49mm | 0.63–0.74 |

### 3.3 解释

- 残差与速度高度相关，说明原始残差主要是**控制器跟踪滞后**，不是接触力。
- PlugCharger 相关较低（0.33–0.36），因为它慢、接触段长；HangCup/StackBowls 快，滞后占主导。
- 直接把残差阈值化会在快速段大量误报；在慢速段又可能被重力/摩擦淹没。
- 这是本轮最重要的负结果：它否定了"残差=力"的 naive 方案，逼出了准静态差分探测。

### 3.4 夹爪 stall：更可靠的弱信号

抽样中可见：

- PlugCharger ep0 f311：left cmd 3.26 / obs 3.61（stall 0.35）；right cmd 1.10 / obs 1.45（stall 0.35）——两侧都夹住插排/插头。
- HangCup：right cmd 0.05 / obs 0.14（接近闭合）；left cmd 4.50 / obs 4.51（张开）——单帧需结合相位判断，不能直接下"没夹到"的结论。
- StackBowls：抓取段开度变化同样可被 stall 逻辑捕获；本轮未逐帧标注，仅作弱证据。

解释：`closure_residual = g* - g` 在抓住/挡住时增大；`g` 本身是物体宽度/硬止点的代理。它不依赖速度，是比 EE 残差更干净的接触/抓取信号。它不是力，但对"有没有夹到/有没有挡住"足够。

### 3.5 对设计的三个结论

1. **准静态差分**：只在低速/稳态用残差；用"探测前后"的差分消掉滞后/重力。
2. **夹爪 stall**：作为几乎免费的抓取/阻塞检测，和视觉进度融合。
3. **仿真特权标签**：官方数据没有力，接触 observer 的力标签只能来自仿真；仿真只用于 observer，不用于策略。

### 3.6 效度威胁

- 样本小（1–4 episodes/dataset），429 限流；不能当全量统计。
- action/state 可能有时间对齐/遥操作适配误差；残差里混着 teleop 目标与测量值的差。
- 没有力 ground truth；只能用夹爪 stall/视觉/相位做弱标签。
- 结论是"原始残差不适合直接当力"，不是"残差里没有接触信息"；准静态差分是下一步验证。

## 4. CARE 架构

### 4.1 设计原则

1. **模型无关**：VLA 只提供 nominal action；CARE 在外部修改/验证，不改 VLA 架构。
2. **接触可观测**：用主动探测把"推不动"变成事件，不依赖力传感器。
3. **人类优先**：human 检测触发让行；安全高于任务完成。
4. **可逆**：任何一步都能回退/重试；undo 检测 + SSG rollback。
5. **确定性服务**：固定计算图、固定 chunk、固定超时；p99 可测。
6. **离线 ROS2**：ROS2 只做回放/编排/安全，不进评测关键路径。
7. **可审计**：大模型唯一；observer 小/可关；所有输入输出留痕。

### 4.3 控制回路

| 层 | 频率 | 作用 |
|---|---:|---|

| Probe Controller | 5–10Hz | 准静态探测；只在接触阶段 |

| SSG | 每 chunk | 成功门控/步骤诊断/回退 |
| Yield Manager | 事件触发 | 让行-回退-恢复 |

### 4.4 状态机

```

  ▲        │          │         │              │                │         │
  │        └──────────┴─────────┴──────────────┴────────────────┴─────────┘
  │                                   │
  │                             YIELD (any state)
  │                                   ▼
  └──────────────────────────── HOLD → RELOCALIZE → ROLLBACK? → RESUME
```

- `CONTACT`：Contact Observer 首次给出 contact_prob > τ_c。
- `PROBE`：Probe Controller 接管最后 1–5mm；VLA 动作被 override。
- `VERIFY`：CARE-SVL 检查释放后的稳定性/位姿。
- `YIELD`：任何状态可被 human/undo 打断；保存 SSG 状态和物体位姿。

## 5. Contact Observer

### 5.1 输入与特征

- 本体：`q_t`（14）、`ee_t`（12）、`g_t`（2）、`g*_t`（2）、`a_{t-1}`（目标）。
- 历史：8–16 帧（0.27–0.53s @30Hz）。
- 视觉：4 路 RGB；腕部 ROI；头部人手检测。
- 语言/相位：SSG 的当前步骤（approach/contact/insert/release）。
- 输出：`contact_prob`、`slip_prob`、`grasp_width`、`human_prob`、`progress`、`contact_normal`。

### 5.2 夹爪 stall 检测

```
closure_residual_t = g*_t - g_t
stall_t = 1[ |closure_residual_t| > τ_s and |g_t - g_{t-1}| < ε ]
grasp_width_t = g_t
```

- `g*` 是命令开度，`g` 是观测开度；`τ_s` 初值 0.3（开度单位），`ε` 初值 0.02。
- `stall=1` 且 `g > g_min + δ`：抓住物体；`g` 接近 `g_min`：空夹/硬止点。
- 闭合过程中 `g` 突然停住：物体挡住；`g` 缓慢下降：软物体/滑移。
- 开爪时 `g` 不增：物体卡住/粘住。
- 标定：官方数据 + 调试槽；用视觉/相位弱标签拟合 `τ_s`、`ε`。

### 5.3 滞后模型（free-space residual predictor）

```
r_t = a_{t-1} - p_t                     # EE 位置残差
r̂_t = f_θ(v_t, a_t, a_{t-1}, q_t, g_t)  # 学习/线性滞后模型
s_t = || r_t - r̂_t ||                   # 去滞后残差
```

- `f_θ` 可以是一个小 MLP/线性模型；输入速度、加速度、关节、夹爪；在 free-space 段训练。
- free-space 段来源：仿真（无力/低力）、官方数据的 approach/retreat 段、SSG 相位。
- 目的不是精确建模，而是**去掉速度主项**；`s_t` 仍然有噪声，所以只作为融合特征之一。

### 5.4 CWM-lite（接触世界模型）

```
x_{t+1}^{(i)} = g_{φ_i}(x_t, a_t),  i=1..K
cwm_error_t = mean_i || x_{t+1}^{(i)} - x_{t+1} ||
cwm_disagree_t = var_i || x_{t+1}^{(i)} - x_{t+1} ||
contact_score_t = cwm_error_t + λ * cwm_disagree_t
```

- 小模型（10–30M）：GRU/Transformer，输入本体状态 `x_t = [q, ee, g]` 子集 + 动作，输出下一状态。
- 训练：官方数据（free-space 加权）+ 仿真（接触标签）；鲁棒损失（Huber）；集成 3–5 个。
- 接触 = 预测误差/分歧变大；不需要力标签。
- 与 force-aware VLA 的关系：ForceVLA2 [S13]、FD-VLA [S14]、HapticVLA [S15]、TAO-Force [S16]、Opt2VLA [S17]、FM-VLA [S18]、CR-VLA-Force [S19]、TaF-VLA [S21]、TacCoRL [S20] 的共同点是把力/触觉作为输入、训练标签或蒸馏目标；FD-VLA/HapticVLA 最接近"无传感器"路线，但仍需要力/触觉训练数据。我们的差异是：**不把力当输入，而把接触当主动探测的事件**；官方数据没有力标签，所以只用仿真力做特权校准，推理靠准静态差分/夹爪 stall/CWM。

### 5.5 视觉接触/进度

- 任务关键点：插头尖/插孔、网线卡扣/端口、拉链滑块、瓶盖标记、碗沿、杯钩。
- 跟踪：CoTracker/SAM2 或轻量关键点回归；10Hz；ROI 由 SSG 相位给出。
- 进度：
  - 插入：`progress = 1 - ||plug_tip - hole|| / ||plug_tip_0 - hole||`。
  - 拔出：`progress = ||plug_t - plug_0|| / L`。
  - 拧盖：`progress = Δθ / 360°`（视觉标记）。
  - 拉链：`progress = ||slider_t - slider_0|| / seam_length`。
  - 堆叠：`progress = 1 - ||bowl_rim - stack_top|| / h`。
- 视觉接触：物体表面变形/遮挡/滑块启动；作为 contact 的弱特征。

### 5.6 人手检测

- 头部相机 + 轻量手检测器（MediaPipe/YOLO-hand）；10–15Hz。
- 特征：手 bbox 与工作区重叠、手到 EE 距离、人脸检测、运动能量。
- `human_prob = σ(w1*hand_conf + w2*overlap + w3*proximity + w4*motion)`。
- 触发条件：`human_prob > τ_h` 连续 3 帧，或手进入 EE 30cm 球。
- 隐私：日志中模糊人脸/手；不做身份识别。

### 5.7 标签

| 来源 | 标签 | 用途 |
|---|---|---|
| 仿真（Isaac Lab/MuJoCo，官方栈 [S28]） | contact force >0.1N、slip、human hand | Contact Observer/CWM 训练 |
| 官方数据 | 夹爪 stall、相位、视觉关键点 | 弱标签/阈值校准 |
| 本地调试槽 | 脚本化探测、人手干扰 | 标定/验证 |
| 红队 | 透明/反光/软物体/遮挡 | 失败模式 |

### 5.8 伪代码

```python
def contact_observer(obs, hist, prev_action, ssg_phase):
    stall, grasp_width = gripper_stall(obs.g, prev_action.g_cmd)
    v = ee_velocity(hist)
    if v < V0:
        r = ee_residual(prev_action, obs)
        r0 = steady_residual(hist)           # last 50ms
        lag_free = norm(r - r0) > TAU_R
    else:
        lag_free = cwm_error(hist, prev_action) > TAU_C
    visual = visual_contact(obs.images, ssg_phase)
    cwm = cwm_error(hist, prev_action)
    contact = sigmoid(w1*stall + w2*lag_free + w3*cwm + w4*visual)
    human = hand_detector(obs.images) or object_moved(obs, hist)
    return ContactState(contact, stall, grasp_width, human, progress)
```

### 5.9 超参初值

| 参数 | 初值 | 说明 |
|---|---:|---|
| V0 | 0.02m/s | 低速门控；低于此值用稳态残差 |
| τ_s | 0.3 | 夹爪 stall 阈值（开度单位） |
| ε | 0.02 | 开度变化阈值 |
| τ_r | 3mm | 稳态残差变化阈值 |
| τ_c | 待标定 | CWM 误差阈值 |
| K | 3–5 | 集成大小 |
| hold | 100ms | 准静态保持 |
| probe Δ | 2mm | 默认探测步长 |

### 5.10 失败模式

- 透明/反光物体：视觉关键点丢失 → 用夹爪 stall/残差兜底。
- 软物体：stall 缓慢变化 → 用进度/视觉。
- 快速运动：残差被滞后污染 → 等低速/稳态。
- 遮挡：视觉丢失 → 用本体 + CWM。
- sim-real gap：CWM 只在仿真训练会过拟合 → 官方数据 free-space 微调 + 保守阈值。

## 6. Probe Controller（ACP-2）

### 6.1 探测原语

| 原语 | 动作 | 用途 |
|---|---|---|
| push | 沿任务轴 +2mm，保持 100ms | 插入/放置到底 |
| pull | 沿轴 −2mm，保持 100ms | 拔出/释放确认 |
| spiral | 垂直平面 8 方向，半径 2–5mm | 找孔/找缝 |
| rotate | ±2°，保持 100ms | 拧盖/对齐 |
| dither | ±1mm，2Hz，0.5s | 解卡/拉链 |
| tap | 1mm 快速点，回位 | 确认表面/清障 |

### 6.2 任务脚本

| 任务 | 相位 | 探测 | 成功判据 |
|---|---|---|---|
| T10 PlugCharger | 插入 | 对准后 push 2mm；不动则 spiral 2–5mm；进入后继续 push | 进度 >0.8 且接触分下降 |
| T26 PlugInEthernet | 插入 | 卡扣对准；push 至 click；pull test 1mm | click/位移 + pull 阻力 |
| T05 DisconnectEthernet | 拔出 | 沿线轴 pull 2mm；不动则加 1mm；弹出后停 | 位移突增 + 接触分下降 |
| T19 ZipUp | 拉链 | 夹滑块；沿缝 pull 2mm + dither；卡住回退 1mm | 滑块进度 >0.9 |
| T14 PourOutMedicine（拧盖） | 拧盖 | rotate ±2°；不动则反向回位再拧 | 角度进度 >0.9 |
| T27 StackBowls | 放置 | 下压 2mm；检查稳态；不稳则 nudge | 位置误差 + 稳定 |
| T01 HangCup | 挂钩 | 对齐钩/沿；下压 2mm；释放 | 杯子稳定悬挂 |

### 6.3 准静态差分算法

```
1. p0 = current EE; hold 100ms; r0 = mean(residual[-50ms])
2. p1 = p0 + Δ (task axis); move; hold 100ms; p1a, r1 = mean(...)
3. Δp = ||p1a - p0||; Δr = ||r1 - r0||
4. if Δp < α||Δ|| and Δr > τ_r:
       blocked/contact; k = Δr / ||Δ||
   else:
       free; continue
5. if blocked and progress not increasing:
       search (spiral/pull/rotate/dither)
```

- `α` 初值 0.5；`τ_r` 初值 3mm；`k` 是相对刚度代理。
- 差分消掉重力/慢漂移；保持消掉瞬态滞后。
- 不做力估算的绝对值，只做相对比较（free vs blocked，硬 vs 软）。

### 6.4 搜索策略

- **Spiral**：8 方向 × 半径 {2, 3.5, 5}mm；每点 push 2mm；选 `k` 最小/进度最大的方向。
- **Pull**：每步 2mm；若 `Δp` 突增且 `Δr` 下降 → 释放；最多 10mm。
- **Rotate**：±2°，4 次；若 `Δθ_visual` 不增 → 反向 1mm 再试。
- **Dither**：±1mm @2Hz，0.5s；用于拉链/卡扣。
- **Tap**：1mm 快速点；用于清障/确认表面。

### 6.5 安全边界

| 项 | 限制 |
|---|---|
| 单次探测幅度 | ≤5mm / ≤5° |
| 单次保持 | ≤200ms |
| 单步探测次数 | ≤2 |
| 单任务探测总时长 | ≤20s |
| 估计接触力 | ≤20N（保守） |
| 夹爪力 | ≤60N |
| 人附近速度 | ≤0.1m/s |
| 人手进入 30cm | 立即停止/让行 |

### 6.6 伪代码

```python
def probe(task, phase, budget):
    for attempt in range(MAX_PROBES):
        if budget.exceeded() or human_near():
            return ABORT
        p0, r0 = settle(hold=0.1)
        delta = task.axis * PROBE_STEP
        p1 = p0 + delta
        move(p1)
        p1a, r1 = settle(hold=0.1)
        if blocked(p0, p1a, r0, r1):
            direction = search(task, p0, r0)
            if direction is None:
                return STUCK
            p1 = p0 + direction
            move(p1)
            p1a, r1 = settle(hold=0.1)
            if not blocked(p0, p1a, r0, r1):
                return FREE
        else:
            return FREE
    return STUCK
```

### 6.7 与 VLA 的集成

- VLA 返回 chunk（4–8）；wrapper 执行前 `k` 个动作。
- 当 `contact_prob > τ_c` 或 SSG 进入 contact 相位，wrapper 用 probe 替换 chunk 的最后 1–2mm。
- probe 成功后，恢复 VLA 的下一个 chunk；失败则回退/重试。
- 这样 VLA 不需要知道 probe；probe 也不需要训练。

### 6.8 恢复

- **Stuck**：后退 2mm，重新对准，再 probe；最多 2 次。
- **Slip**：重新夹取；用 stall/视觉确认。
- **False contact**：连续 2 次 probe 都是 free，则忽略 contact 分。
- **Timeout**：放弃当前步，交给 SSG 诊断/下一任务；不硬撑。

## 7. Yield Manager（CARE-YR）

### 7.1 人类干扰分类

| 类型 | 例子 | 检测 |
|---|---|---|
| move object | 把碗/包/杯子移走 | 物体关键点位移 >5mm 且非机器人动作 |
| undo step | 拉开拉链、拧回盖子、拿走叠好的碗 | SSG 谓词从 true 变 false |
| occlude | 手挡住相机/物体 | 手 bbox + 视觉丢失 |
| touch robot | 手碰手臂/夹爪 | 接触分突变 + 手 bbox |
| hand near | 手进入工作区 | 手 bbox/距离 |
| tool drop | 物体掉落 | 物体关键点突降 + 声音（无音频） |

### 7.2 检测

- 手检测：`human_prob > τ_h` 连续 3 帧。
- 物体运动：关键点位移 >5mm，且机器人当前动作不能解释。
- 接触突变：free-space 相位出现高 contact 分。
- SSG undo：当前步谓词 false，且上一步谓词 true。

### 7.3 让行协议

```
1. stop: 取消当前 chunk，冻结 VLA
2. release: 打开夹爪（避免拖拽）
3. retreat: 沿来路后退 10cm；保持
4. wait: 手离开工作区连续 0.5s，或 5s 超时
5. relocalize: 检测物体位姿；与保存的位姿比较
6. decide:
   - moved: 更新目标位姿，重新接近
   - undone: SSG rollback 到上一步，重做
   - occluded: 继续等/换视角
   - gone: 放弃该物体/任务降级
7. resume: 重新接近 + probe + verify
```

### 7.4 Undo 判定

- 保存每个完成步骤的物体状态（位姿/开合/进度）。
- 如果完成步骤的谓词变为 false：
  - 拉链被拉开 → 回退到 zip 步；
  - 盖子被拧回 → 回退到 turn 步；
  - 碗被拿走 → 回退到 stack 步；
  - 插头被拔 → 回退到 insert 步。
- 回退只回一步，不重置整个任务；避免时间浪费。

### 7.5 恢复

- 重新接近用 PGL/OPT；接触用 probe 重新建立。
- 如果人手还在，保持等待；时间预算不足则优雅失败（不要撞人）。
- 记录 yield 事件、时长、恢复结果，供 CSC 审计。

### 7.6 伪代码

```python
def on_human(obs, ssg, budget):
    stop(); open_gripper(); retreat(0.10)
    if not wait_clear(timeout=5.0):
        return HOLD
    pose = relocalize(obs)
    if moved(pose, ssg.saved_pose):
        ssg.update_target(pose)
    if ssg.is_undone(obs):
        ssg.rollback(1)
    if budget.low():
        return ABORT
    return RESUME
```

### 7.7 安全/伦理

- 人附近：EE 速度 <0.1m/s；不主动接触人；不向人脸/头部方向运动。
- 夹爪：释放优先；不夹人；夹爪力 <60N。
- 探测：人进入 30cm 立即停止；探测幅度 ≤5mm。
- 日志：记录 human_prob、事件、动作；模糊人脸。

### 7.8 失败模式

- **False positive**：背景人手/视频里的人 → 多帧 + 工作区 ROI + 冷却。
- **Human stays**：5s 超时 → 保持/放弃；不硬闯。
- **Object gone**：无法恢复 → 任务降级/失败；记录。
- **Undo 误判**：谓词噪声 → 双阈值 + 视觉确认。

## 8. ROS2-CARE 离线靶场

### 8.1 为什么 ROS2 不在评测路径

- 评测接口是 WebSocket/msgpack 的 `get_action(obs)`（[S6]），不是 ROS2 topic/service。
- 在 `get_action` 里加 ROS2 序列化/发现/调度，只会增加 p99 抖动；评测端也不需要。
- 所以 ROS2 只做**离线靶场**：录包、回放、编排、安全监控、A/B；不参与提交。

### 8.2 节点图

| `safety_guard` | 限速/停止/否决 | `/care/contact`、`/care/yield` | `/care/action_safe` |
| `ssg_monitor` | 步骤门控/诊断 | `/care/obs`、`/care/action_safe` | `/care/ssg` |
| `recorder` | rosbag2 录制 | 全部 | bag |
| `replay` | 回放 | bag | 全部 |
| `eval` | 指标 | bag/日志 | 报表 |

| Topic | 类型 | QoS |

### 8.4 Lifecycle N 端口

- `policy_server` 用 managed node：configure（加载模型/warmup）→ activate（开始服务）→ deactivate（停止）→ cleanup。
- N 个端口 = N 个 session/namespace；状态隔离（obs history、SSG、probe 预算）。
- 健康检查：心跳/延迟/异常率；失败端口重启，不影响其他端口。
- 参考 ROS2 managed nodes 教程（[S27]）。

### 8.5 rosbag2 录制/回放

```

```

- 回放：同一 bag 跑 baseline/CARE，比较成功率/延迟/动作规律性。
- 参考 ROS2 rosbag2 教程（[S26]）。

### 8.6 接触监控/安全守卫

- `contact_observer` 发布 contact/slip/grasp/human/progress。
- `safety_guard` 订阅 human/contact；human 进入 30cm → 限速/停止；contact 超限 → 停止。
- `yield_manager` 发布 yield；`safety_guard` 有最终否决权。
- 可视化：rviz2 标记接触点/人手/工作区；方便红队。

### 8.7 延迟测量

- 在 `policy_server` 内打点：obs 收 → 预处理 → 推理 → 后处理 → 发布。
- 记录 p50/p95/p99、jitter、超时次数。
- 在 bag 里对齐 obs/action 时间戳；离线复算。
- 目标：p99 <100ms；若 >150ms，换 DM0/减 chunk。

### 8.8 启动草图

```bash

```

### 8.9 不要做

- 不要在 `get_action` 里创建 ROS2 node/等待 discovery。
- 不要把图像通过 ROS2 多跳传输再推理。
- 不要让 ROS2 的 QoS/executor 影响 p99。
- 不要把 ROS2 当成"评测接口"写进提交说明。

## 9. 伦理审查 / 接触安全案（CSC）

### 9.1 范围

- 任务：32 个桌面任务，重点接触/人机交互任务。
- 人：官方 human 干扰操作员、调试槽人员、实验室人员。
- 数据：官方 Apache-2.0 数据；本地调试数据；不采集 L2L 人类数据（默认）。

### 9.2 风险矩阵

| 风险 | 场景 | 概率 | 影响 | 缓解 |
|---|---|---|---|---|
| 夹伤 | 夹爪夹到人手 | 低 | 高 | 人手检测/释放/力限 |
| 碰撞 | 手臂撞到人 | 低 | 高 | 限速/停止/工作区 |
| 物体飞出 | 插入/拔出弹飞 | 中 | 中 | 低速/小步/护目 |
| 摔倒 | 长程任务/急停 | 低 | 高 | 预算/姿态守卫 |
| 隐私 | 视频含人脸 | 中 | 中 | 模糊/不识别 |
| 数据滥用 | 自采人类数据 | 低 | 高 | IRB/同意/默认 OFF |
| 评测作弊 | 硬编码/读评测器 | 低 | 高 | 审计/留痕 |

### 9.3 限制

| 项 | 限制 | 依据 |
|---|---|---|
| 人附近 EE 速度 | ≤0.1m/s | 保守（ISO/TS 15066 参考）[S25] |
| 准静态探测 | ≤5mm/≤5° | 本方案 |
| 估计接触力 | ≤20N | 保守估计 |
| 夹爪力 | ≤60N | Dex1-1 5–120N 的下半区 [S10] |
| 人机间距 | ≥30cm | 工作区守卫 |
| 人脸/头部 | 不接触 | ISO/TS 15066 禁止 |
| 单任务探测 | ≤20s | 180s 预算 |

ISO/TS 15066:2016 给出协作机器人 quasi-static/transient 接触的生物力学限值（[S25]）；G1 不是认证协作机器人，本赛也不是协作场景。我们只把它当**保守参考**，不做认证宣称。

### 9.4 人检测/响应

- 手检测 + 人脸检测 + 运动能量；10–15Hz。
- 人手进入工作区/30cm → 限速/停止；持续 → yield。
- 人手接触机器人 → 立即停止/释放/后退。
- 不朝人脸方向运动；不主动接触人。

### 9.5 数据治理

- 官方数据 Apache-2.0（[S8][S9]）；遵守许可/署名。
- 本地调试数据：只采机器人/物体，不采人脸；如含人，模糊/删除。
- L2L 人类数据：默认 OFF；如做，需 IRB/知情同意/安全存储/可撤回。
- 日志：最小化；不识别个人；保留期限。

### 9.6 评测诚信

- 不硬编码 task ID/slug/场景坐标。
- 不读取评测器内部状态/随机种子/未来帧。
- 不利用 API 漏洞/时间窗口/重复提交。
- 所有输入输出/模型版本/配置留痕；模型卡披露 CARE 组件。
- 单模型审计：大模型唯一；observer 小/可关；确定性代码列清。

### 9.7 审查清单

| 项 | 检查 |
|---|---|
| 安全包络 | 速度/力/间距/探测幅度有硬限制 |
| 人检测 | 手/脸/运动；误检/漏检测试 |
| 让行 | stop/release/retreat/wait/resume 全链路 |
| 数据 | 许可/同意/隐私/存储 |
| 诚信 | 无硬编码/无评测器读取/留痕 |
| 红队 | 透明/反光/软物体/遮挡/人手 |
| 回滚 | SSG rollback 不破坏已完成的步 |
| 失败 | 超时/掉件/人不在 → 优雅失败 |

### 9.8 Go/No-Go

- 人检测漏检率 <5%（脚本化测试）；误检 <20%。
- 让行恢复成功率 >50%；human 轴 +10pp。
- 无安全违规（碰撞/夹人/超速）。
- 审计通过（模型卡/日志/配置）。

## 10. 服务与延迟（LDS）

### 10.1 模型组合

| 模型 | 规模 | 优势 | 风险 | 用途 |
|---|---:|---|---|---|
| WLA-1.0-Base | 6B | 域匹配、Dex1、Apache-2.0 | 延迟/显存 | 默认 |
| DM0 | 2B | 小、快、generalist 37.3% | 域匹配弱 | 延迟不达标时 |
| GigaBrain-0.7 | 3.5B | 37k 小时、三系统 | 延迟/算力 | 备选（若可部署） |

### 10.2 Chunk 权衡

| chunk | 调用频率 | 接触反应 | 延迟风险 | 建议 |
|---:|---:|---|---|---|
| 4 | 高 | 好 | 中 | 接触任务 |
| 8 | 中 | 中 | 低 | 默认 |
| 16 | 低 | 差 | 低 | 自由空间/长程 |

`action_chunk_size` 在 metadata 里声明；如果只能固定一个值，选 8；wrapper 内部只执行前 4 个，再查询（如果 API 允许）。若 API 执行整段，选 4。

### 10.3 固定计算图

- 固定 batch=1、固定分辨率、固定 chunk；不做动态路由/动态 batch。
- warmup 10–20 次；CUDA graphs / TensorRT / ONNX（如可行）；`torch.inference_mode`。
- 预处理/后处理用固定 buffer；避免 Python 分支抖动。
- 模型/权重启动时加载；不在 `get_action` 里加载/编译。

### 10.4 N 端口隔离

- 每端口独立 obs history/SSG/probe 预算；共享模型权重（只读）。
- 队列：每端口一个；超时丢弃旧请求；不阻塞其他端口。
- 健康检查：心跳、p99、异常率；失败重启。
- 目标：p99 <100ms；jitter <20ms；异常率 <0.1%。

### 10.5 动作规律性

- 关节/EE 限幅；速度/加速度限制；jerk 限制。
- 夹爪命令平滑；不跳变；不超范围。
- NaN/Inf/越界检查；异常时 hold 上一帧/停止。
- 记录动作分布/异常率；在 bag 里可复算。

### 10.6 测量

| 指标 | 目标 | 方法 |
|---|---|---|
| p50/p95/p99 | <100ms p99 | 服务器打点 |
| jitter | <20ms | 时间戳差 |
| 超时率 | <0.1% | 计数 |
| 动作异常率 | <0.1% | NaN/越界/跳变 |
| 恢复时间 | <1s | 端口重启 |

### 10.7 预期（待测，不是承诺）

| 配置 | 预期 p99 | 备注 |
|---|---:|---|
| WLA 6B, chunk 8, A100 | 80–150ms | 需实测；可能超 |
| WLA 6B, chunk 4, A100 | 120–200ms | 调用更频繁 |
| DM0 2B, chunk 8, A100 | 40–80ms | 需实测 |
| DM0 2B, chunk 4, A100 | 60–120ms | 接触友好 |

如果 WLA p99 >150ms，换 DM0；如果 DM0 精度不够，考虑 WLA + chunk 8 + 只执行前 4 个（若 API 允许）。

### 12.4 统计

- 320 trials；配对种子（如可设）；bootstrap 95% CI。
- 主比较：CARE vs baseline 的总成功率；次比较：human/接触子集。
- 调试槽：小样本，只看方向/失败模式，不做显著性。
- 若 CI 跨 0，不宣称提升；继续迭代或回退。

### 12.5 Go/No-Go

| 门 | 条件 | 不达标 |
|---|---|---|
| G1 | E4 AUROC ≥0.80 | 回退 stall+SVL |
| G2 | stall 检出 ≥90% | 纯视觉进度 |
| G3 | E6 human +10pp | 只做安全停止 |
| G4 | E7 p99 <100ms | 换 DM0/减 chunk |
| G5 | E8 总 +3pp | 保守版提交 |
| G6 | 安全事件 0 | 停止提交，修安全 |

### 12.6 回退

- 保守版：SSG + PGL/OPT + CARE-SVL（无 probe/CWM/YR）。
- 最小版：stall + 安全停止 + SVL。
- 任何回退都要在模型卡/报告里写清。
