# 第 13 轮（新循环第 1 轮）· TF-ARM：把 UniBot 从「54 维全身 VLA」还原成「16 维双臂桌面问题」

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮承接第 10–12 轮，不推倒第 12 轮 CHUNK-SERVO；三个灵感词是「机器人操作系统」「数据规模」「机械臂」。核心判断：CHUNK-SERVO 解决了「最后 3 厘米要不要闭环」，本轮要解决「这 3 厘米的闭环到底能不能被 7-DoF 手臂执行、动作在哪个坐标系里定义、33k 演示到底覆盖了几个域」。

## 0. 先给结论：不是「再大一点的 VLA」，而是「一个被全身动作空间拖累的 16 维双臂问题」

截至 2026-10-31，官网榜单仍是 8 个模型，MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。但第 12 轮已经证明：这个榜单是「预览/脚本生成」的，不能当实测 SOTA，也不能反推任务难度。所以本轮不从名次找创新点，而从**官方数据本身**找结构性事实。

我把 7 个代表任务的 `meta/episodes` 元数据和 HangCup 的 63,999 帧逐帧数据拆开看，得到四个会改变方案的事实：

1. **动作空间的绝大部分是静态的。** HangCup 64k 帧上，`action.lower_body` 与 `observation.state.lower_body` **逐帧完全相等**（max|diff|=0），`action.left_leg/right_leg` 同理；`action.pivot` 在所有抽查任务里几乎是常量 `[0,0,0,0,0.15,0,0.738]`；腰部动作相对状态的最大差只有 **0.016 rad**。挑战赛真正动态的只有 **2×7 臂 + 2×1 夹爪 = 16 维**（外加 3 维腰部毫米级微调），不是 WLA 的 54 维全身动作。
2. **头部相机的位姿可以从 `lower_body` 精确恢复。** 63,999 帧上，`T_torso→d435` 的平移 `[0.0576, 0.0175, 0.4299] m` 和旋转**方差为 0**；`waist_state_joint` 到 `state_torso` 的欧拉角是**精确线性映射（R²=1.0）**；而 `lower_body[-3:]` 与 `waist_state_joint` 逐帧完全相等。也就是说，官方 API 给的 15 维 `lower_body` 已经足够在线重建头相机 TF，不需要 `state_d435`。
3. **33k 集不是 33k 个独立域。** 抽查 7 个任务，每个任务只有 **5–8 个 session、2–4 个机器人 ID**；HangCup 1043 集只来自 6 个 session。同一 session 内相机平移标准差只有 **0.7–3.0 mm**，不同 session 的相机均值差 **1.5–11.2 mm / 0.28–1.27°**；而不同 session 的平均 EE 高度差可达 **8.1 cm**（HangCup）——**真正变的是桌面/工件高度，不是相机**。随机按帧划分会把同一 session 的相邻帧泄漏到验证集，离线指标会虚高。
4. **7-DoF 手臂经常贴着关节限位工作。** 按 G1 29-DoF URDF 的名义限位对齐，ToolboxStorage 有 **58%** 的 episode 腕部某一关节进入限位 2% 以内（腕 pitch 20%），FoldTowel 为 **27%/13%**，PlugInEthernet 的腕部三关节为 **1–8%**；HangCup / ToolboxStorage / PlugInEthernet 的肘关节距下限都 **<1%**。一个只在 EE 空间输出绝对位姿、完全不懂关节限位的策略，会在最后几厘米把 IK 推到饱和。

所以本轮的押注是 **TF-ARM**：

> **把动作统一到「桌面系」（TFA），用 MCAP/ROS2 的 TF 几何主干做会话级数据覆盖与免标注视角增广，再用一个 7-DoF 的确定性 QP（ARM-QP）把 VLA 的 EE 目标投影成限位内、速度内、可执行、腕部可见的关节轨迹；VLA 仍是唯一学习模型，TF/QP/MCAP 都是确定性基础设施。**

一句话：**UniBot 不是「54 维全身 VLA 不够大」，而是「16 维双臂桌面问题被 54 维动作空间、base 系动作和 5–8 个 session 的数据分布拖累了」。**

三个可验证创新点（不是三个宏大名目）：

1. **TFA（Table-Frame Actions）**：离线把每条演示的 EE/关节动作变换到桌面系，在线用首帧双目估计桌面平面再变回 base 系；因为动作不再依赖相机/机器人位姿，视角/机器人位姿扰动可以**免标注**地做几何增广。
2. **ARM-QP（7-DoF 可行性投影）**：用 URDF + 关节限位 + 速度限位 + 奇异值裕度，把 VLA 的 EE chunk 投影成可行关节轨迹；7-DoF 的 1 维零空间用于「离限位更远 / 可操作度更高 / 腕部相机对准目标」。
3. **MCAP-COVER（会话级覆盖索引）**：把 32 个 HF 数据集索引成带 TF、同步流、覆盖度量的 MCAP/rosbag2 风格数据层；按 session/robot 划分，按覆盖度选数据，按延迟注入做回放；它是离线数据资产，不是第二个模型。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **机器人操作系统** | 用 ROS2/TF 的数学（URDF→base→torso→head/wrist→EE）做几何主干；用 MCAP/rosbag2 做数据/回放；在线只保留 4×4 变换和小 QP，不把 ROS2 塞进提交接口 | 不把 websocket `PolicyService` 改成 ROS2 topic；不引入 MoveIt 全栈；不依赖 ROS2 运行时 |
| **数据规模** | 33k 集 / 169h 的「有效规模」= episode × 域多样性；抽查任务只有 5–8 个 session；用 session 划分、覆盖度采样、桌面系免标注增广、16 维动态动作损失掩码来提高有效规模 | 不收集更多同 session 演示；不训第二个生成模型；不做完整 sim-to-real |
| **机械臂** | 7-DoF 冗余 + 关节/速度/奇异值约束的 ARM-QP；接触段用关节空间或 EE 可行性过滤；腕部限位感知 | 不做力矩/触觉闭环（API 没有）；不做 6D 物体位姿网络；不做逐任务策略 |

## 1. 本轮新核实的事实（只列会改变方案的）

### 1.1 赛事与榜单：规则没变，榜单仍是「预览」

官方挑战赛页（2026-10-31 抓取）明确：32 项真实桌面任务，**32,000 条演示、169 小时**；任务覆盖抓取、放置、双手协调。首页/榜单仍是 8 个模型，榜首 29.7%；`runs.html` 显示 256 条「模型×任务」运行记录，但详情页仍是「测试视频占位，后续可替换为真实视频文件」。这与第 12 轮的取证一致：**榜单只能当难度/方向信号，不能当实测 SOTA 或任务难度表。**

规则侧沿用第 12 轮已核实的参赛手册：同一模型完成全部任务、每任务 10 次、5 类泛化各 2 次、单次 180 s、按平均成功率再按步骤分、跨 N 台机器人、8765 起 N 个连续端口、每端口 `reset()` 隔离、另有不计分单任务通道。本轮不重复抓手册全文，但所有设计都按这些约束检查。

### 1.2 API：`joint`/`ee` 二选一，`lower_body` 是隐藏的几何入口

提交 README（2026-10-31 复核）关键点：

- 观测四路 RGB 480×640；双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str`。
- 动作 `control_space` 仅 `"joint"` 或 `"ee"`，二者互斥；共享 `action.left_gripper/right_gripper/pivot`。
- `joint` 模式返回 `action.left_arm/right_arm [7]`；`ee` 模式返回 `action.left_ee_pose_gripper_base/right_ee_pose_gripper_base [6]`（**绝对目标位姿**）。
- `action_chunk_size` 固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action`。
- **没有 depth、camera_info、force/torque、tactile**；`action.pivot` 只写「Lower-body / pivot target」，没有逐维定义。
- 评测端逐调用记录延迟、波动、动作统计规律，作为可信度的一部分。

关键推论：`lower_body[15]` 的最后 3 维是腰部关节，且与数据集 `waist_state_joint` 完全一致；这 3 维足以恢复头相机 TF。**API 没给相机外参，但给了恢复外参所需的关节状态。** 这是 TFA 和 ARM-QP 的接口基础。

### 1.3 数据：32k 集 / 169h，但每个任务只有 5–8 个 session

数据集集合（HuggingFace `unitreerobotics/unibot-v1-challenge-dataset`，2026-10-31 复核）共 32 个 LeRobot v3.0 数据集。HangCup 的 `meta/info.json` 与 dataset card 给出：

- 四路视频：`head_stereo_left/right`、`wrist_left/right`，480×640，30 fps。
- 头双目已校正，基线 **58.2526 mm**，`fx≈282.37`；腕部相机没有内参矩阵。
- 状态含 `left/right_arm [7]`、`left/right_gripper [1]`、`lower_body [15]`、`state_torso [6]`、`state_d435 [6]`、`waist_state_joint [3]`、`recomputed_ee_valid [1]`，以及 base/torso 系的 EE 位姿。
- 动作含关节、EE、夹爪、`lower_body`、`pivot [7]`、`base_command [4]`、`gripper_controls [4]` 等；`pivot` 的维名是 `vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height`。
- Dex1 夹爪范围 **5.5–0.0（open→close）**。

抽查 7 个任务的 `meta/episodes`（2026-10-31，共 **7,158 集**）：

| 任务 | episodes | sessions | 机器人 ID | 同 session 相机平移 std | 跨 session 相机平移 std | 跨 session 相机旋转 std | session 均值 EE z 范围 |
|---|---:|---:|---:|---:|---:|---:|---:|
| HangCup | 1043 | 6 | 3 | 1.7 mm | 4.0 mm | 0.51° | 8.1 cm |
| PlugInEthernet | 1009 | 6 | 4 | 2.0 mm | 3.1 mm | 0.28° | 2.3 cm |
| ZipUp | 1006 | 6 | 4 | 2.8 mm | 3.1 mm | 0.51° | 6.7 cm |
| ArrangeTestTubes | 1004 | 7 | 2 | 2.1 mm | 2.6 mm | 0.94° | 3.8 cm |
| FoldTowel | 1053 | 7 | 2 | 3.0 mm | 11.2 mm | 1.27° | 3.3 cm |
| ToolboxStorage | 1064 | 5 | 2 | 2.5 mm | 1.5 mm | 0.35° | 0.7 cm |
| PourOutMedicine | 979 | 8 | 3 | 2.1 mm | 3.2 mm | 0.86° | 5.0 cm |

> 相机列是标量离散度：先算每个 session 的相机平移均值，再算这些均值到总体均值的位移范数，最后取标准差；within 列则是 session 内各 episode 均值到该 session 均值的位移范数标准差。旋转列是各 session 相机 R 的相对旋转角的标准差。

这张表说明三件事：

- **同 session 内视角几乎不动**（1.7–3.0 mm），所以「1043 集」不等于「1043 个视角」；有效域数量更接近 5–8。
- **跨 session 的相机差异不大**（1.5–11.2 mm / 0.28–1.27°），但**桌面/工件高度差异更大**（session 均值 EE z 差 0.7–8.1 cm）。位置泛化的主要矛盾可能不是相机，而是桌面高度。
- **必须按 session 划分验证集**；随机按帧划分会把相邻帧泄漏，离线成功率虚高。

### 1.4 我们自己的离线测量：TF 可恢复、动作 16 维、腕部贴限位

以下都是我们在公开数据上做的分析（B 级，可复现；不是官方声明）：

**（a）头相机 TF 可精确恢复。** 在 HangCup 的 63,999 帧上：

- `T_torso→d435` 平移 = `[0.0576, 0.0175, 0.4299] m`，逐帧 std = 0；旋转 std = 0。头相机与 torso 刚性固连。
- `state_torso` 的 rpy 对 `waist_state_joint` 做线性回归，**R² = 1.0**；`lower_body[-3:]` 与 `waist_state_joint` 逐帧 max|diff| = 0。
- 因此：`T_base_d435 = T_base_torso(q_waist) @ T_torso_d435`，在线只需要 `lower_body[-3:]`。

**（b）动作空间的 38/54 维是静态的。** HangCup 64k 帧：

- `action.lower_body == observation.state.lower_body`（max|diff| = 0）；`action.left_leg/right_leg` 同理。
- `action.pivot` 的 episode 均值 = `[0, 0, 0, 0, 0.15, 0, 0.738]`，跨 episode std ≤ 0.011（FoldTowel 的 `pivot_4` 例外，std 0.057）。
- `action.waist_action_joint` 与 `state.waist_state_joint` 的 max|diff| = 0.016 rad。
- 真正动态的只有 **2×7 臂 + 2×1 夹爪 = 16 维**；腰部 3 维是毫米级微调；腿/躯干/高度/pivot 基本是「保持」。

**（c）腕部贴限位。** 按 G1 29-DoF URDF 名义限位（`g1_29dof_with_hand_rev_1_0.urdf`）对齐，左臂「进入限位 2% 以内」的 episode 比例：

| 任务 | 肘 | 腕 roll | 腕 pitch | 腕 yaw |
|---|---:|---:|---:|---:|
| HangCup | 1% | 0% | 0% | 0% |
| PlugInEthernet | 2% | 1% | 3% | 8% |
| ZipUp | 0% | 0% | 0% | 4% |
| ToolboxStorage | 0% | 1% | 20% | **58%** |
| FoldTowel | 0% | 8% | 13% | **27%** |

- 肘关节的全局最小 margin：HangCup 0.6%、ToolboxStorage 0.7%、PlugInEthernet 0.9%（距下限 <1%）。
- **重要陷阱**：数据集 feature 里的关节名顺序是 `[shoulder_pitch, shoulder_roll, shoulder_yaw, elbow, wrist_yaw, wrist_roll, wrist_pitch]`，但观测范围显示第 5 维（j4）能到 ±1.97 rad，匹配 URDF 的 `wrist_roll`（±1.9722），不匹配 `wrist_yaw`（±1.6144）。**不要相信数据集里的关节名，按 URDF 限位/运动行为对齐。** 这是任何 FK/QP 落地前的第一道检查。

**（d）EE 标签有效，但 `min-z` 归一化不够。** 抽查 7 个任务的 `recomputed_ee_valid` 全部为 1（0 个 invalid episode），EE 标签可用。我们试了一个最便宜的「相对最低点」归一化（用每集 EE z 均值减 z 最小值）来消除桌面高度差：

- 4/7 任务跨 session 方差下降：HangCup 2.61→0.99 cm、PlugInEthernet 0.85→0.42、FoldTowel 1.25→0.86、PourOutMedicine 1.72→0.75。
- 3/7 反而变大：ZipUp 2.15→3.10、ArrangeTestTubes 1.24→1.44、ToolboxStorage 0.27→0.53。

**结论：朴素的 min-z 归一化不够，必须用真正的桌面平面估计（头双目点云 + RANSAC）或首帧标定。** 这条本轮被剪枝，不进入主方案，只作为 G2 的对照。

- G1 29-DoF URDF：`unitree_ros/robots/g1_description/g1_29dof_with_hand_rev_1_0.urdf`，含 7-DoF 臂、关节限位、速度/effort 限制。
- G1 MuJoCo XML：`unitree_mujoco/unitree_robots/g1/g1_29dof.xml`。

- 官方还新开了 `unitree_robotskills`（LLM agent + 技能框架，G1-D/R1-D），说明官方也在往「技能组合」走；但挑战赛要求单模型，不能用多技能/多模型拼装。

### 1.6 头部方案的做法与瓶颈（沿用第 12 轮判断，补上本轮视角）

| 模型家族 | 公开路线 | 本轮补充的瓶颈 |
|---|---|---|
| **MolmoAct2** | action reasoning + adaptive depth；3D 空间推理强 | 仍是 base 系 EE chunk；没有显式 7-DoF 限位/奇异值处理 |
| **WALL-OSS-0.5** | 4B VLA（3B VLM + action expert） | progress 高 ≠ success；最后一步失败就 0 分；4B 实时性 |
| **DreamZero** | 14B video-diffusion world-action model | 世界模型预测未来，不解决「现在关节超限 2°」 |
| **π0.5** | 开放世界泛化 VLA | 接触密集任务的精度；远程延迟 |
| **GigaBrain-0** | 世界模型生成数据 + VLA | 生成数据物理保真度；最后 3 厘米 |
| **GR00T N1.5** | NVIDIA 通用人形 VLA | 任务特定精度；数据覆盖 |

共同点：**都是「动作 chunk + base 系 EE」；没有人把「桌面系动作 + 7-DoF 可行性 + 会话级覆盖」做成一个执行层。** 这正是 TF-ARM 的切入点。

## 2. 诊断：三个错配叠在一起

```text
训练：base 系 EE 动作 + 5–8 个 session + 相机/桌面高度固定
测试：N 台机器人 + 位置/背景/人为扰动 + 桌面高度可能变
        │
        ├─ 坐标系错配：动作吸收了机器人/相机/桌面位姿，测试一变就分布外
        ├─ 运动学错配：EE 目标可能超限位/近奇异，低层 IK 饱和，最后 3cm 失败
        └─ 数据错配：33k 集高度相关，随机划分泄漏，更多同 session 数据边际收益低
```

三个「不是」：

1. **不是语义不够**：32 个任务的语言/物体类别并不复杂；头部双目 + 33k 演示足够。
2. **不是 chunk 不够长**：第 12 轮已经论证 30 步开环是问题；本轮补上「即使 chunk 对了，关节也可能不可达」。
3. **不是模型不够大**：6B/14B 已经在榜首附近；再大不解决限位、坐标系、数据域。

## 3. 方法：TF-ARM

### 3.1 总架构

```text
                    ┌──────────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1)      │
                    └───────────────┬──────────────────────────┘
                                    │ websocket: obs / action chunk
                                    ▼
                    ┌──────────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)            │
                    │  ├─ TF backbone: lower_body → head cam   │
                    │  ├─ TFA: table-frame action adapter      │
                    │  ├─ CHUNK-SERVO: 30-step plan + 5-step   │
                    │  ├─ ARM-QP: 7-DoF feasibility projector  │
                    │  └─ action adapter: joint/ee + pivot     │
                    └───────────────┬──────────────────────────┘
                                    │ async, batched
                                    ▼
                    ┌──────────────────────────────────────────┐
                    │  Shared VLA server (GPU)                 │
                    │  UnifoLM-WLA-1.0 / VLA-0, 30-step        │
                    └──────────────────────────────────────────┘

离线：
  HF 32 datasets ──► MCAP-COVER 索引（TF/同步/覆盖度）
                   ├─ session-aware split
                   ├─ table-frame action 重标注
                   ├─ 免标注视角/机器人位姿增广
                   └─ 延迟注入回放（0/50/100/150 ms）
```

- **唯一学习模型**：VLA（官方 WLA 或 VLA-0）。
- **确定性控制器**：TF、TFA、ARM-QP、CHUNK-SERVO 的伺服；无学习权重。
- **数据资产**：MCAP-COVER；不是第二个模型，是索引/回放/增广。
- **在线开销**：一次 4×4 变换 + 7 变量 QP；目标 p99 < 2 ms（CPU）。

### 3.2 TFA：Table-Frame Actions

**定义桌面系** `T_base_table = [R_table | t_table]`：z 轴垂直桌面向上，x 轴指向机器人前方，y 轴左手系。训练时对每条 episode 估一次 `T_base_table`，把 EE/关节动作变到桌面系；测试时用首帧（或前 2–3 帧）估计一次，再把 VLA 的桌面系动作变回 base 系。

训练：

```text
for each episode:
    T_base_table = estimate_table(episode.head_stereo, episode.state_d435)
    for each frame:
        a_table = inv(T_base_table) @ a_base
        e_table = inv(T_base_table) @ e_base
    train VLA on (images, language, state) -> a_table
```

测试：

```text
T_base_table = estimate_table(obs.head_stereo, obs.lower_body)
a_table = VLA(obs)
a_base = T_base_table @ a_table
a_cmd = ARM_QP(a_base, obs)
```

为什么有效：

- **桌面高度/机器人位姿变化被吸收**：同一「把杯子挂到架子」的动作在桌面系里几乎不变，base 系里会随桌子高度整体平移。
- **免标注增广**：如果只扰动相机/机器人位姿（场景不变），桌面系动作标签不变；可以对头部图像做平面单应变换生成新视角，动作标签原样复用。这是「数据规模」最便宜的扩张方式。
- **和 CHUNK-SERVO 兼容**：DG-KEYFRAME 的相对目标本来就可以存成 `T_table_target` 与 `T_target_ee*`，伺服误差也在桌面系里算。

桌面平面估计：

1. 头双目校正后算视差：`Z = f b / d`，反投影到相机系，再用 `T_base_d435` 变到 base 系。
2. RANSAC 拟合平面 `n^T p + d = 0`；取 `z_table = -n`（朝上），`x_table` 为机器人前方在平面上的投影，`y_table = z_table × x_table`。
3. 若桌面被遮挡/反光导致内点 < 阈值，回退到「数据集同任务 session 中位数桌面高度 + 当前 base 位姿」；再失败就回退 base 系动作，不硬做。

**可选扩展：canonical view warp。** 用 `H = K (R + t n^T / d) K^{-1}` 把头部图像 warp 到虚拟相机（例如桌面上方 0.5 m、俯角 45°），再喂 VLA；这样测试视角和训练视角更一致。只做小扰动（±5 cm / ±5°），避免物体高度引起的视差伪影。这个作为 P7，先过 G5 再上线。

### 3.3 ARM-QP：7-DoF 可行性投影

给定当前关节 `q ∈ R^7`、当前 EE 位姿 `T_ee`、目标 `T_ee*`（来自 VLA+TFA+伺服），先算 6D 误差 twist `v*`，再解：

```math
\begin{aligned}
\min_{\dot q,\, s}\quad &
\|J(q)\dot q - v^*\|_W^2
+ \lambda \|\dot q\|^2
+ \mu \|\dot q - \dot q_{\text{prev}}\|^2
+ \rho \|s\|^2 \\
\text{s.t.}\quad &
\dot q_{\min} \le \dot q \le \dot q_{\max} \\
& q_{\min}+\epsilon \le q + \dot q\,\Delta t \le q_{\max}-\epsilon \\
& \|J(q)\dot q - v^*\|_\infty \le s \\
& \sigma_{\min}(J(q)) \ge \sigma_0 \quad \text{(check / soft penalty)}
\end{aligned}
```

- 7 变量、14 个箱约束 + 少量线性约束；OSQP/active-set 在 30 Hz 下 p99 < 1 ms。
- 若不可行：把 `v*` 按 `α ∈ [0,1]` 缩放，直到可行；仍不可行就保持当前关节（安全 hold）。
- **零空间**：7-DoF 对 6D 任务有 1 维零空间。用

```math
\dot q = J^+ v^* + (I - J^+ J)\,k\,\nabla g(q)
```

其中 `g(q)` 是标量姿态目标：

```text
g(q) = w_lim  * Σ_j log(margin_j(q))          # 远离关节限位
     + w_man  * log(σ_min(J(q)))              # 远离奇异
     + w_cam  * alignment(target, wrist_cam)  # 腕部相机对准目标（需标定）
```

- `w_cam` 需要腕部相机相对 EE 的外参；数据集没给腕部内参，先做一次棋盘格/手眼标定；标定不过就令 `w_cam=0`，只做限位/奇异。
- **EE 可行性过滤**：如果提交用 `ee` 模式，先解 QP 得 `q_next`，再 `T_ee_feasible = FK(q_next)`，返回 `T_ee_feasible` 而不是原始 `T_ee*`。这样 API 仍是 `ee`，但目标已经被拉回可行域。
- **joint 模式**：如果提交用 `joint`，直接返回 `q_next`。接触任务（腕部贴限位）可能 joint 模式更稳；但 joint 模式对 embodiment 更敏感。**必须用单任务通道 A/B，不要凭直觉选。**

为什么 ARM-QP 不是「第二个模型」：它没有学习权重，只有 URDF、限位、QP；输入是 VLA 的动作，输出是投影后的动作。合规模式 C2（确定性控制器）。

### 3.4 MCAP-COVER：会话级覆盖索引

把每个 HF 数据集转成 MCAP/rosbag2 风格的分片：

```text
/challenge/tf                 # base→torso→head_left/right→wrist_left/right→EE
/challenge/observation/*      # 4 路图像、关节、EE、lower_body、language
/challenge/action/*           # joint/ee、gripper、pivot
/challenge/meta               # task, session, robot_id, episode, fps
/challenge/coverage           # 每集覆盖度量
```

每集覆盖度量：

```text
cov(ep) = [
  cam_pose_std,            # 头相机在 episode 内的位姿标准差
  table_height,            # 桌面平面相对 base 的 z
  workspace_hull_volume,   # EE 轨迹凸包体积
  min_joint_margin,        # 最贴近限位的关节 margin
  contact_fraction,        # 夹爪闭合/低速/近目标的帧比例
  session_id, robot_id
]
```

用途：

1. **按 session/robot 划分**：leave-one-session-out，避免相邻帧泄漏。
2. **覆盖度采样**：贪心 max-min 选 session/episode，优先补齐相机位姿、桌面高度、EE 工作空间；不是「越多越好」。
3. **任务诊断**：哪些任务只有 1–2 个 session、哪些任务桌面高度跨度大、哪些任务腕部贴限位——这些决定 TFA/ARM-QP 的投入顺序。
4. **回放压测**：按 chunk 执行、注入 0/50/100/150 ms 延迟、注入动作噪声，测 p99 和恢复。

### 3.5 DYN-16：只学 16 维动态动作

数据已经说明：腿/躯干/高度/pivot 基本是保持，真正变的是 16 维双臂+夹爪（外加 3 维腰部微调）。训练策略：

- 保留官方 WLA 的 54 维输出头，但在损失里**掩码静态维**：只对 16 维动态动作 + 3 维腰部算 loss；静态维用「当前状态」作为目标或直接不加 loss。
- 推理时静态维回填数据集同任务中位数（pivot）或当前状态（lower_body/legs）；双臂+夹爪用模型输出。
- 好处：不改变模型结构、不违反单模型；把有限的数据/梯度集中到真正影响成功的维度；减少 base/腿抖动。
- 风险：如果测试时 base/waist 需要动（例如人为干扰把机器人推歪），静态回填会失效；用 `lower_body` 的当前状态做 hold，并保留一个小范围的 waist 预测。

### 3.6 和 CHUNK-SERVO 的接法

```text
VLA:     每 30 步（1 s）产出 30 步桌面系 plan；后台线程；不阻塞 get_action
TFA:     plan_table → plan_base（用当前 T_base_table）
Servo:   每 5 步（167 ms）用腕部/头部图修正一次；误差在桌面系
ARM-QP:  把 5 步 EE 目标投影成可行关节轨迹（或可行 EE 目标）
API:     action_chunk_size = 5；evaluator 执行 5 步后再次调用
```

状态机沿用第 12 轮：`INIT → PLAN → SERVO → CONTACT → RECOVER → DONE`；新增：

- `CONTACT` 段优先用 joint 模式或 EE 可行性过滤；法向缩幅、切向保留。
- `RECOVER` 段重估 `T_base_table`（人可能移动了桌子/物体）；如果桌面估计失败，回退 base 系并降增益。
- 任何 QP/标定失败 → 回退上一组合法动作或安全 hold；绝不返回 NaN/错误形状。

### 3.7 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | MCAP-COVER 只离线生成覆盖度/相位标签；线上只有 VLA | 最低 | 保守首选 |
| C2 确定性控制器 | TFA/ARM-QP 是几何/控制律，无学习权重 | 低；需向官方说明 | 主推 |
| C3 同 checkpoint 特征 | 目标描述子用 VLA 同一 checkpoint 的 encoder | 低–中 | 需要强描述子时用 |

禁止：加载第二个学习策略/残差网络/独立视觉编码器做在线决策。TFA/ARM-QP/MCAP 都不加载第二个模型。

## 5. 竞赛策略：把 320 trials 投到「运动学压力 × 域缺口 × 伺服杠杆」最高的任务

### 5.1 任务组合（先验，待单任务通道更新）

- **A 档：ARM-QP/TFA 优先**：ToolboxStorage（腕 yaw 58% 贴限位）、FoldTowel（27%/13%，但变形任务要小心）、PourOutMedicine（27%）、PlugInEthernet（腕部 1–8% + 肘 <1%）、HangCup（肘 <1%，且桌面高度跨 session 8.1 cm）、ZipUp（6.7 cm 高度差）、ArrangeTestTubes（7 个 session）。
- **B 档：VLA/TFA 优先**：FruitSorting、ColorArrangement、OrganizeTools、PlacePhotoFrame、OrganizeBookshelf、PickOutBatteries、RemovePinnedNote 等以语义/分类/摆放为主的任务。
- **C 档：观察**：单任务通道里 `p_t` 接近 0 且失败在早期感知/抓取的任务；不投 ARM-QP。

优先级：

```text
priority_t = q_t * Δ_arm * Δ_tfa / cost_t
```

- `q_t`：失败发生在最后 3 厘米的比例（先验，单任务通道更新）；
- `Δ_arm`：ARM-QP 的条件增益（用腕部贴限位比例做先验，ToolboxStorage/FoldTowel/PourOutMedicine 高）；
- `Δ_tfa`：TFA 的条件增益（用跨 session 桌面高度差做先验，HangCup/ZipUp/PourOutMedicine 高）；
- `cost_t`：目标库/标定/调参成本。

### 5.2 单任务通道协议（不计分，但决定是否烧正式提交）

1. 选 5 个代表任务：ToolboxStorage、PlugInEthernet、HangCup、ZipUp、FoldTowel。
2. 每个任务 5 次 A/B：base 系 vs TFA；EE vs joint；QP on/off。
3. 指标：成功率、步骤分、耗时、p99 延迟、关节限位违规、IK 失败、恢复次数。
4. 通过：≥3/5 任务 +10pp；FoldTowel 不回归 >5pp；p99 ≤150 ms。
5. 再扫 `H_c ∈ {3,5,8}` 和 `image_resize` 两档；选 p99 与成功率的最佳折中。
6. 最后才跑 32×10 正式评测。

### 5.3 提交节奏

- **W0**：官方 WLA + API adapter + chunk 30 基线；单任务通道跑 1 个任务，确认 token/`pivot`/关节顺序。
- **W1**：离线 TF/MCAP；G0/G1/G2；桌面平面估计。
- **W2**：ARM-QP 仿真；G4；joint vs ee。
- **W3**：TFA 微调 + DYN-16 loss；单任务 A/B；G3/G6/G7。
- **W4**：全量干跑；N 端口；p99/内存；G8。
- **W5**：最终提交；保留回滚开关。

如果允许多次提交：先交安全基线锁「更早提交」tie-break，再交 TF-ARM。如果只允许一次：W4 后再交，不用正式 320 trials 做未验证的 A/B。

## 6. 与第 12 轮的关系：保留、升级、剪枝

**保留**：

- CHUNK-SERVO 的 30 步规划 + 5 步伺服 + DG-KEYFRAME 相对目标 + 数字孪生标定 RTT/增益。

- base 系动作 → **桌面系动作（TFA）**；

**剪枝**：

- **不做朴素的 min-z 归一化**：本轮试了，3/7 任务反而变大；改用真正的桌面平面估计。
- 不做从零训 VLA/World Model；官方 WLA 已开源 6B 基座。
- 不做完整 sim-to-real 策略训练；数字孪生只做 QP/延迟/扰动风洞。
- 不做第二个学习模型/残差策略；TFA/ARM-QP 是确定性层。
- 不做 6D 物体位姿网络；用桌面系相对目标 + 局部特征。
- 不做力矩/触觉闭环；API 没有。
- 不做 32 个任务各训一个策略；规则禁止，且不泛化。
- 不把 ROS2 当提交接口；官方只认 `PolicyService` 的 Python/websocket 接口；ROS2/TF 只在离线/内部使用。

## 7. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 桌面平面估计失败 | TFA 动作整体偏移 | RANSAC + 内点阈值 + 数据集同任务先验；失败回退 base 系 |
| 测试机器人相机外参不同 | 头相机 TF 偏差 | 首帧标定/重投影；用 `T_torso→d435` 数据集常数作先验；误差大关 TFA |

| 静态 pivot 回填在测试时失效 | 下身体不动/姿态错 | 用 `lower_body` 当前状态 hold；保留小范围 waist 预测；G8 |
| 桌面系增广引入伪影 | 视觉分布偏移 | 限幅 ±5 cm/±5°；只用平面单应；G5 |
| 单模型解释 | 被判定第二个模型 | C1/C2/C3；提交材料写清楚；TFA/QP 无学习权重 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、320 trials SE≈2.4pp；重复实验 |
| session 泄漏 | 离线指标虚高 | leave-one-session-out；按 robot_id/日期分组 |
| 过度拟合抽查 7 任务 | 结论不外推 | 先跑 7 任务，再扩到 32；所有结论标 B/C 级 |

## 8. 一句话押注

**先用 MCAP 覆盖率索引证明 33k 集只有 5–8 个域，再把动作统一到桌面系（TFA）做免标注几何增广，最后用 7-DoF ARM-QP 把 EE 目标投影成限位内、可执行、腕部可见的关节轨迹——这是 CHUNK-SERVO 真正落地所需要的执行层，也是在不违反单模型规则下最便宜的涨点路径。**

# 第 13 轮产物 · TF-ARM 技术报告

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「TF-ARM」的工程化产物；承接第 12 轮 CHUNK-SERVO，不替换它。

## 0. 结论与边界

### 0.1 一句话结论

官方数据里，**WLA 的 54 维布局中，挑战赛可观测到的动态维度只有 16 维双臂+夹爪（外加 3 维腰部微调）；腿、躯干、高度、pivot、灵巧手维度在挑战赛数据里是保持或无关**；**头相机 TF 可以由 `lower_body[-3:]` 精确恢复**；**33k 集只来自每任务 5–8 个 session、2–4 个机器人**；**腕部关节在接触任务中经常进入限位 2% 以内**。因此，最便宜的执行层创新不是再训一个更大的 VLA，而是：

1. **TFA**：把动作统一到桌面系，做免标注视角/机器人位姿增广；
2. **ARM-QP**：用 7-DoF 限位/速度/奇异值约束把 EE 目标投影成可行关节轨迹；
3. **MCAP-COVER**：按 session/robot 划分与覆盖度采样，避免 33k 集的「伪规模」。

VLA 仍是唯一学习模型；TF/QP/MCAP 都是确定性基础设施。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、URDF 直接核实 | 32 任务/32k 集/169h、API 键、URDF 限位、数据集字段 |
| B | 我们在公开数据上做的分析，可复现 | 16 维动态动作、TF 常数、session 统计、腕部贴限位比例 |
| C | 设计假设，需 G0–G9 验证 | TFA 涨点、ARM-QP 涨点、桌面平面估计精度 |

### 0.3 本轮不做什么

- 不从零训 VLA/World Model；官方 WLA 已开源 6B 基座。
- 不做完整 sim-to-real 策略训练；数字孪生只做 QP/延迟/扰动风洞。
- 不做第二个学习模型/残差策略；TFA/ARM-QP 是确定性层。
- 不做 6D 物体位姿网络；用桌面系相对目标 + 局部特征。
- 不做力矩/触觉闭环；API 没有。
- 不把 ROS2 当提交接口；官方只认 `PolicyService` 的 Python/websocket 接口。
- 不做 32 个任务各训一个策略；规则禁止，且不泛化。
- 不把朴素 min-z 归一化当主方案；本轮已实测 3/7 任务反而变差。

### 1.2 提交 API（A）

提交 README（2026-10-31 复核）关键点：

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB 480×640 |
| 本体 | 双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str` |
| 动作空间 | `control_space` 仅 `"joint"` 或 `"ee"`，二者互斥 |
| 共享动作 | `action.left_gripper [1]`、`action.right_gripper [1]`、`action.pivot [7]` |
| `joint` 动作 | `action.left_arm [7]`、`action.right_arm [7]` |
| `ee` 动作 | `action.left_ee_pose_gripper_base [6]`、`action.right_ee_pose_gripper_base [6]`（绝对目标位姿） |
| chunk | `action_chunk_size ≥ 1`，固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action` |
| token | `metadata.token` 握手校验一次；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile** |
| 监控 | 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分 |

关键推论：

- `lower_body[15]` 的最后 3 维是腰部关节；数据集验证它与 `waist_state_joint` 逐帧完全一致。**API 没给相机外参，但给了恢复外参所需的关节状态。**
- `action.pivot` 只写「Lower-body / pivot target」，没有逐维定义；数据集里 `pivot` 的维名是 `vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height`，但抽查任务中它几乎是常量。**不要把 pivot 当自由变量乱猜。**
- `ee` 模式是绝对目标位姿；如果 VLA 输出相对动作，adapter 必须先 compose 到当前 EE 绝对位姿，再叠加伺服/投影。第 12 轮已给出这个陷阱。

### 1.4 我们的离线测量（B）

#### 1.4.1 TF 可精确恢复

在 HangCup 的 63,999 帧上：

```text
T_torso→d435 translation = [0.0576, 0.0175, 0.4299] m   (std = 0, range = 0)
T_torso→d435 rotation    = constant                     (std = 0, max angle = 0)
state_torso.rpy ~ waist_state_joint                      (linear regression R² = 1.0)
lower_body[-3:] == waist_state_joint                     (max|diff| = 0)
```

因此：

```math
T_{\text{base}\to d435}
= T_{\text{base}\to torso}(q_{\text{waist}})\;T_{\text{torso}\to d435}
```

在线只需要 `obs.lower_body[-3:]`，不需要 `state_d435`，也不需要额外相机外参（但换机器人时要用首帧重标定，见 G0）。

#### 1.4.2 动作空间 16 维动态

HangCup 64k 帧：

| 检查 | 结果 |
|---|---|
| `action.lower_body` vs `observation.state.lower_body` | max\|diff\| = 0 |
| `action.left_leg/right_leg` vs state | max\|diff\| = 0 |
| `action.waist_action_joint` vs state | max\|diff\| = 0.016 rad |
| `action.pivot` episode 均值 | `[0, 0, 0, 0, 0.15, 0, 0.738]` |
| `action.pivot` 跨 episode std | ≤0.011（FoldTowel `pivot_4` std 0.057） |
| 真正动态的维度 | 2×7 臂 + 2×1 夹爪 = **16 维**（外加 3 维腰部微调） |

这与 WLA 的 54 维动作布局（第 12 轮已核实）形成鲜明对比：**挑战赛不是 54 维全身问题，而是 16 维双臂桌面问题。** 全身动作头里大量维度在「保持」，会浪费数据/梯度，并引入 base/腿抖动。

#### 1.4.3 腕部贴限位

按 G1 29-DoF URDF 名义限位（`g1_29dof_with_hand_rev_1_0.urdf`，2026-10-31）对齐，左臂「进入限位 2% 以内」的 episode 比例：

| HangCup | 1% | 0% | 0% | 0% |
| PlugInEthernet | 2% | 1% | 3% | 8% |
| ZipUp | 0% | 0% | 0% | 4% |
| ToolboxStorage | 0% | 1% | 20% | **58%** |
| FoldTowel | 0% | 8% | 13% | **27%** |

左臂全局最小 margin：

| 任务 | 肘 margin | 腕 roll margin | 腕 pitch margin | 腕 yaw margin |
|---|---:|---:|---:|---:|
| HangCup | 0.6% | 12.6% | 18.3% | 0.8% |
| PlugInEthernet | 0.9% | 0.2% | 0.1% | 0.1% |

负值表示观测值略微超出名义限位（可能是 URDF 版本/关节顺序/零点差异），不是「数据错了」，而是提醒：**必须用官方 G1 29-DoF URDF 复核关节顺序和零点**。

**关节顺序陷阱**：数据集 feature 名是 `[shoulder_pitch, shoulder_roll, shoulder_yaw, elbow, wrist_yaw, wrist_roll, wrist_pitch]`，但观测范围显示 j4 能到 ±1.97 rad，匹配 URDF 的 `wrist_roll`（±1.9722），不匹配 `wrist_yaw`（±1.6144）。**不要相信数据集里的关节名，按 URDF 限位/运动行为对齐。** 这是任何 FK/QP 落地前的第一道检查（G0）。

|---|---:|---:|---|
| HangCup | 2.61 | 0.99 | 改善 |
| PlugInEthernet | 0.85 | 0.42 | 改善 |
| ZipUp | 2.15 | 3.10 | 变差 |
| ArrangeTestTubes | 1.24 | 1.44 | 变差 |
| FoldTowel | 1.25 | 0.86 | 改善 |

### 2.2 核心三点详情

#### P1 · TFA（Table-Frame Actions）

**动机**：base 系 EE 动作把「桌面高度、机器人 base 位姿、相机视角」都吸收进动作标签。抽查任务跨 session 的 session 均值 EE z 差 0.7–8.1 cm，而相机差异只有 1.5–11.2 mm；测试时如果桌面高度/机器人位置变了，base 系动作就是分布外。桌面系动作只依赖「目标相对桌面」的几何，天然吸收这些变化。

**与现有方案的差异**：头部方案（MolmoAct2/WALL/DreamZero/π0.5/GigaBrain/GR00T）公开路线都是 base 系 EE 或关节 chunk；没有看到「首帧双目估桌面平面 + 桌面系动作 + 免标注几何增广」的组合。TFA 不是新模型，是动作表示/数据增广层。

**技术可行性**：

- 头双目已校正，基线 58.2526 mm，`fx≈282.37`；可算视差/点云。
- `T_torso→d435` 常数（63,999 帧 std=0）；`waist→torso` 精确线性（R²=1.0）；`lower_body[-3:]` 可用。
- 桌面平面 RANSAC 是成熟方法；失败可回退 base 系。
- 动作变换是 4×4 矩阵乘法，CPU 微秒级。

**所需资源**：

- 数据：现成 32 个 HF 数据集；离线重标注不需要新采集。
- 算力：CPU 做 TF/平面/索引；1×24 GB GPU 做 WLA action-head 微调。
- 接口：不需要改 API；在线只多做一次 4×4 变换。
- 人力：1 人几何/标定，1 人 VLA/训练，1 人评测。

**落地步骤**：

1. 离线：对每条 episode 用 `state_d435` + 头双目估 `T_base_table`；把 `action.*_ee` 和关节动作变到桌面系。
2. 训练：用桌面系动作微调 WLA action head；输入仍为原图 + 语言 + 状态（可选把 `T_base_table` 的 6D 作为额外 token）。
3. 在线：首帧估 `T_base_table`；VLA 输出桌面系动作；变回 base 系；送 ARM-QP。
4. 增广：对头部图像做 ±5 cm/±5° 的平面单应扰动；桌面系动作标签不变。
5. 评测：单任务通道 A/B（base vs TFA）；G1/G2/G6。

**风险**：桌面反光/遮挡导致平面估计失败；测试机器人相机外参不同；物体高度引起单应视差。缓解：RANSAC 内点阈值 + 数据集同任务先验 + 回退 base 系；限幅增广；G0/G1/G5。

#### P2 · ARM-QP（7-DoF 可行性投影）

**动机**：7-DoF 手臂在接触任务中经常贴限位（ToolboxStorage 腕 yaw 58% episode 进入限位 2% 以内；FoldTowel 27%；PlugInEthernet 腕部 1–8%；肘 margin <1%）。EE 空间策略输出的绝对目标可能超出关节限位/近奇异，低层 IK 饱和，最后 3 厘米失败。ARM-QP 把「语义目标」投影成「物理可行目标」。

**与现有方案的差异**：头部方案没有公开的 7-DoF 限位/奇异值/零空间处理；它们依赖低层 IK 或关节控制器。ARM-QP 是确定性、无学习权重的执行层，符合单模型规则。

**技术可行性**：

- 7 变量 QP（14 个箱约束 + 少量线性约束），OSQP/active-set 在 30 Hz 下 p99 <1 ms。
- URDF 提供限位/速度/effort；FK/Jacobian 可用 Pinocchio/KDL 或自写。
- 零空间 1 维（7-DoF vs 6D 任务），可用于限位裕度/可操作度/腕部对准。
- 失败可回退「缩放 Cartesian 步长」或「保持当前关节」。

**所需资源**：

- 算力：CPU（每端口一个 QP 实例，或共享求解器）。
- 数据：URDF + 演示轨迹（用于仿真回放）；不需要新数据。
- 接口：`joint` 模式直接返回关节；`ee` 模式用 FK 生成可行 EE 目标。
- 人力：1 人控制/优化。

**落地步骤**：

1. 用 G1 29-DoF URDF 对齐关节顺序/零点；在 MuJoCo 里做单关节小幅运动自检。
2. 实现 FK/Jacobian + damped least squares + QP；先在演示轨迹上加扰动回放（E4）。
3. 仿真扫 `σ0`、速度上限、零空间权重；测 p99/限位违规/跟踪误差。
4. 单任务通道 A/B：QP on/off；joint vs ee；G4/G6/G7。
5. 全量干跑：每端口独立 QP 状态；G8。

**风险**：QP 延迟；不可行时抖动；腕部相机外参未知导致 `w_cam` 不可用；joint 模式跨 embodiment 不泛化。缓解：fast path DLS；不可行 hold；`w_cam=0` 回退；先 A/B 再选控制空间。

#### P3 · MCAP-COVER（会话级覆盖索引）

**动机**：33k 集听起来很大，但每任务只有 5–8 个 session、2–4 个机器人；同 session 相机 std 1.7–3.0 mm。随机按帧划分会把相邻帧泄漏到验证集，离线指标虚高；按 episode 平均也不等于按域泛化。需要把「域」显式建模。

**与现有方案的差异**：头部方案不公开数据划分/覆盖度；MCAP-COVER 把 TF、同步流、覆盖度量做成可查询索引，直接服务于 session split、覆盖度采样、回放压测。

**技术可行性**：

- MCAP/rosbag2 是成熟格式；Python `mcap`/`rosbag2_py` 可写。
- 元数据已有 session/robot/date（`task_id` 里含 robot_id/date）。
- 覆盖度量可从 `meta/episodes` 的 stats 直接算，不需要解码视频。
- 回放可注入延迟/动作噪声，模拟远程 API。

**所需资源**：

- 存储：视频 1–2 TB；只存关键帧/元数据可降到 <100 GB。
- 算力：16–32 CPU 核做转换/索引。
- 接口：离线，不影响提交。
- 人力：1 人数据工程。

**落地步骤**：

1. 解析 32 个数据集的 `meta/info.json`、`meta/episodes`、`tasks.parquet`。
2. 写 MCAP 分片：TF、4 路图像、状态、动作、语言、meta、coverage。
3. 建 session/robot 索引；leave-one-session-out 划分。
4. 覆盖度采样：贪心 max-min 选 session/episode；输出训练清单。
5. 回放：chunk 执行 + 延迟注入；G1/G2/G8。

**风险**：转换成本/存储；MCAP 工具链版本；只做离线不直接涨点。缓解：先只索引元数据（<1 GB），视频按需解码；把 MCAP 当分析工具，不阻塞提交。

## 3. 问题形式化

### 3.1 动作空间与动态维度

挑战赛 API：

```text
joint: 2×7 arm + 2×1 gripper + 7 pivot = 23D
ee:    2×6 ee   + 2×1 gripper + 7 pivot = 21D
```

数据审计（HangCup 64k 帧）：

```text
dynamic dims = 2×7 arm + 2×1 gripper = 16D
waist micro  = 3D (|Δ| ≤ 0.016 rad)
static/hold  = lower_body/legs (action == state), pivot ≈ constant
```

因此训练/推理可以只关注 16D + 3D 腰部；pivot 用数据集同任务中位数；lower_body/legs 用当前状态 hold。

### 3.2 TF 链

```math
T_{\text{base}\to torso}(q_w)
= \begin{bmatrix} R(\mathrm{rpy}_{\text{torso}}(q_w)) & t_{\text{torso}} \\ 0 & 1 \end{bmatrix}
```

其中 `q_w = lower_body[-3:]`，`rpy_torso = A q_w + b`（离线拟合，R²=1.0），`t_torso` 近似常数（HangCup std ~0.0001 m）。

```math
T_{\text{base}\to d435}
= T_{\text{base}\to torso}(q_w)\;T_{\text{torso}\to d435}
```

`T_torso→d435` 为常数：平移 `[0.0576, 0.0175, 0.4299] m`，旋转常数。

### 3.3 TFA

训练：

```math
a^{\text{table}} = T_{\text{base}\to table}^{-1}\,a^{\text{base}}
```

测试：

```math
a^{\text{base}} = T_{\text{base}\to table}\,a^{\text{table}}
```

`T_base→table` 由首帧头双目点云拟合平面得到；失败回退 base 系。

### 3.4 ARM-QP

```math
\begin{aligned}
\min_{\dot q,\, s}\quad &
\|J(q)\dot q - v^*\|_W^2
+ \lambda \|\dot q\|^2
+ \mu \|\dot q - \dot q_{\text{prev}}\|^2
+ \rho \|s\|^2 \\
\text{s.t.}\quad &
\dot q_{\min} \le \dot q \le \dot q_{\max} \\
& q_{\min}+\epsilon \le q + \dot q\,\Delta t \le q_{\max}-\epsilon \\
& \|J(q)\dot q - v^*\|_\infty \le s \\
& \sigma_{\min}(J(q)) \ge \sigma_0 \quad \text{(check / soft penalty)}
\end{aligned}
```

不可行时：

```text
for alpha in {1.0, 0.75, 0.5, 0.25, 0.0}:
    solve QP with v* = alpha * v*
    if feasible: break
if not feasible: hold q
```

### 3.5 零空间

```math
\dot q = J^+ v^* + (I - J^+ J)\,k\,\nabla g(q)
```

```text
g(q) = w_lim  * Σ_j log(margin_j(q))
     + w_man  * log(σ_min(J(q)))
     + w_cam  * alignment(target, wrist_cam)
```

`J^+ = J^T (J J^T + λI)^{-1}`（damped）。

### 3.6 桌面平面

头双目校正后：

```math
Z = \frac{f\,b}{d},\qquad
X = \frac{(u-c_x)Z}{f_x},\qquad
Y = \frac{(v-c_y)Z}{f_y}
```

RANSAC 拟合：

```math
\min_{n,d} \sum_{i\in\text{inliers}} (n^T p_i + d)^2,\qquad \|n\|=1
```

取 `z_table = -n`（朝上），`x_table` 为机器人前方在平面上的投影，`y_table = z_table × x_table`。

### 3.7 单应增广

平面上的相机运动：

```math
H = K\left(R + \frac{t\,n^T}{d}\right)K^{-1}
```

对头部图像做 `warpPerspective`；动作标签在桌面系不变。限幅 `R` 为 ±5°、`t` 为 ±5 cm，控制物体高度引起的视差。

### 3.8 覆盖度

```math
\mathrm{cov}(e) =
\left[
\sigma_{\text{cam}}(e),\;
z_{\text{table}}(e),\;
V_{\text{hull}}(e),\;
\min_j \mathrm{margin}_j(e),\;
f_{\text{contact}}(e)
\right]
```

session 级覆盖 = 该 session 内 episode 覆盖的分布。选数据用贪心 max-min：

```text
S = {}
while |S| < budget:
    e* = argmax_e min_{s in S} ||cov(e) - cov(s)||
    S.add(e*)
```

### 4.3 `get_action` 伪代码

```python
class TFARMPolicy:
    def get_action(self, obs):
        self._tick(obs)

        # 1) 几何主干
        T_base_table = self.table_estimator.update(obs)  # 首帧估计，失败回退 None
        T_base_cam = self.tf.head_camera(obs.lower_body)

        # 2) VLA 规划（桌面系或 base 系，取决于训练）
        plan = self._get_plan(obs)  # (H, 16/21/23)

        # 3) CHUNK-SERVO：5 步切片 + 视觉修正
        a_ff = plan[self.plan_idx:self.plan_idx + self.H_c]
        if self.mode == "SERVO" and self.goal is not None:
            delta = self.servo.compute(obs, self.goal, T_base_table)
            a_ff = compose(a_ff, delta, frame="table" if T_base_table else "base")

        # 4) 桌面系 → base 系
        if T_base_table is not None:
            a_base = transform_action(a_ff, T_base_table)
        else:
            a_base = a_ff

        # 5) ARM-QP 投影
        a_cmd = self.arm_qp.project(a_base, obs, self.control_space)

        # 6) 静态维回填
        a_cmd = self.adapter.fill_static(a_cmd, obs)  # pivot, lower_body, legs
        return self.adapter.to_api(a_cmd, obs, self.token)
```

def head_camera_tf(lower_body):

def table_frame_from_stereo(left, right, K, b):
    disp = stereo_match(left, right)
    Z = K[0, 0] * b / disp
    P_cam = backproject(left, Z, K)
    P_base = T_BASE_D435 @ P_cam
    n, d = ransac_plane(P_base)
    z = -n / np.linalg.norm(n)
    x = normalize(project_on_plane(forward_base, z))
    y = np.cross(z, x)
    return make_transform_from_axes(x, y, z, point_on_plane)

### 4.5 QP 伪代码

```python
def arm_qp(q, T_target, T_current, dt, limits, control_space):
    T_err = inv(T_current) @ T_target
    v_star = log6(T_err) / dt

    for alpha in [1.0, 0.75, 0.5, 0.25, 0.0]:
        qdot, feasible = solve_box_qp(
            J=J(q),
            v=alpha * v_star,
            q=q,
            qdot_min=limits.qdot_min,
            qdot_max=limits.qdot_max,
            q_min=limits.q_min + EPS,
            q_max=limits.q_max - EPS,
            dt=dt,
            sigma_min=limits.sigma_min,
        )
        if feasible:
            break

    if not feasible:
        return hold(q)

    q_next = q + qdot * dt
    q_next = q_next + nullspace_posture(q, qdot, target=T_target)
    if control_space == "joint":
        return q_next
    return FK(q_next)
```

### 5.3 统计

- 总分：`S = (1/32) Σ_t p_t`，`p_t` 为任务 t 的 10 次平均。
- 320 trials 下 `p≈0.25` 的单次标准误约 `sqrt(0.25×0.75/320) ≈ 2.42 pp`。
- 单任务 5 次 A/B 只能看方向，不能看显著性；用配对差值 + bootstrap 95% CI。
- 不要用 +1–2 pp 做结论；至少 3/5 任务 +10 pp 才提交模块。

## 8. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 桌面平面估计失败 | TFA 动作偏移 | RANSAC + 内点阈值 + 数据集先验；回退 base |
| 测试机器人相机外参不同 | 头相机 TF 偏差 | 首帧重标定；数据集常数作先验；误差大关 TFA |
| 关节名/顺序不一致 | FK/QP 用错关节 | 按 URDF 限位/行为对齐；单关节自检；G0 |
| QP 延迟 | p99 超预算 | 7 变量箱约束 QP；DLS fast path；p99 ≤2 ms |
| QP 不可行 | 抖动/停住 | 缩放 v*；hold；回退 clamp |
| joint 模式不泛化 | 换机器人失败 | 先 A/B；默认 ee + 可行性过滤 |
| 静态 pivot 失效 | 下身体姿态错 | 用当前状态 hold；保留小范围 waist 预测 |
| 单应增广伪影 | 视觉分布偏移 | 限幅 ±5 cm/±5°；只用平面单应；G5 |
| 单模型解释 | 被判第二个模型 | C1/C2/C3；TFA/QP 无学习权重；材料写清 |
| session 泄漏 | 离线虚高 | leave-one-session-out；按 robot/date 分组 |
| 过度外推 7 任务 | 结论不成立 | 先 7 任务，再扩 32；标 B/C 级 |
| 评测噪声 | 假阳性 | 配对 A/B + bootstrap + 重复实验；SE≈2.4 pp |
