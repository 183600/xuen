# 第 2 轮（UniBot 线 · 第 2 轮；本轮灵感：「开放词汇」×「推理延迟」）

> **承接声明（不重新基线化）**：第 1 轮已建立 UniBot 线并完成奠基：定义 U1–U12、引理 L1–L7、实验 E601–E618、创新点 IP-01–IP-08。本轮全部沿用并封存编号；新增 U13–U23、L8–L14、E619–E636、IP-09–IP-14。第 1 轮的三条硬结论继续作为约束：终态成功是唯一计分货币；"通用"实为技能向量；断点集中在最后一环（对齐/插入/旋转）。
> **情报纪律**：本轮不引入新的外部事实断言。赛事口径沿用第 1 轮已核实的来源（teaser 榜、官方 README、32 个 LeRobot 数据集）；方法侧只引用公开方法的通用名称（开放词汇检测/分割、anytime inference、语义缓存、排队论），不新增未核验 URL。检索环境日期 2026-11-20。

## 0. 一句话

第 1 轮把"抓握"变成了可观测隐变量；本轮修它留下的两个真问题——**隐变量在未见物体上不可信（开放词汇）**、**要把泛化算出来就必须付推理算力（推理延迟）**——办法是：**语义理解放慢环、闭环控制留快环、延迟当可分配预算**，得到 **UniBot-OPAL**。

## 1. 直觉（先说人话，再给严谨定义）

### 1.1 「开放词汇」：真正的开放不是"认识更多物体"，而是"认识更多部件与功能"

第 1 轮的任务 token 是 32 类闭集，抓握真值来自已见物体的间接标签。赛题 5 类泛化里有一条正是"未见物品"，此时：

- 闭合类别词表必然把新物体映射到最近的旧类，**错误恰好发生在最需要正确的地方**；
- 而"抓取/插入"在开放世界里并不依赖物体类别，依赖的是**部件与功能**：有没有可夹的薄边、可握的把手、可插入的槽、可拧的盖、可倾倒的开口。

所以开放词汇操作的正确抽象是 **部件–功能（part–affordance）开放集合**，而不是物体类别开放集合。语言指令给意图（"把电池拿出来"），视觉开放词汇给**可执行部位**（电池仓凸缘、可夹边缘、槽口），两者合成才得到可执行的动作条件。类别是封闭世界的人类习惯，部件是开放世界的物理事实。

同理，**技能词表也应当开放**：不是 32 个任务各一个专家，而是"动词 × 部件功能 × 空间关系"的组合（拿起/放置/打开/倾倒/插入/旋转 × 把手/盖子/槽/边沿/开口 × 里/上/旁/下）。组合空间随部件词表增长而**乘性扩张**，这正好把第 1 轮"每专家至少服务 2 个任务"的约束推到开放世界。

### 1.2 「推理延迟」：它不是要最小化的成本，而是"必须花完但不能超"的预算

第 1 轮已量化：任务内 `corr(时长, 成功) ≈ −0.011`，episode 时长 43.7–45.2 s，"做得快"没有红利；而评测端把 per-step 延迟当作**可信度审计**（要求延迟平滑、动作良构、不做不规则交互）。这推出一个反直觉但关键的策略结论：

> **延迟本身不计分，超预算/抖动才扣分。故最优策略不是"更快"，而是在固定、平滑、合规的节拍内，把尽可能多的算力花在提高成功率上。**

于是"推理延迟"从工程约束升级为**可分配的推理预算**：接近/搬运等简单相位少算，抓握/对齐/插入等断点相位多算（第 1 轮已证明断点集中在插入/旋转/细粒度摆放）。但有一个强约束：**外部观察到的节拍必须稳定**——内部 anytime 计算要藏在"固定节拍整形器"后面，否则会被判定为不规则交互。

### 1.3 合成：开放词汇与推理延迟是一对**结构性对立**

开放词汇需要大模型逐帧做 grounding/分割/指代解析，延迟随开放度上升；控制闭环又要求高频反馈。两者直接耦合会互相拖死。第 1 轮没撞上这堵墙，是因为它默认"语义条件"廉价且闭集。

本轮的解耦 = **双频环 + 语义缓存 + 节拍恒定的算力调度**：

- **慢环（语义，1–3 Hz）**：开放部件/功能 grounding + 指代解析 + 组合技能检索，产出**带置信度与失效条件的语义令牌**；
- **快环（控制，按 chunk）**：只吃缓存语义令牌 + 本体感觉，输出动作块，其延迟与语义模型大小**解耦**；
- **缓存层**：仅当场景变化足够大、相位切换、或置信度过低时重算，把开放词汇的昂贵成本**摊到多个控制步**；
- **调度层**：在恒定外部节拍下，按相位的"成功价值"分配内部算力（anytime：先粗后精，deadline 前必须给答案）。

一句话：**用"慢而开放"的语义喂"快而闭环"的控制，用缓存摊销，用节拍整形合规。**

## 2. 边界与反驳（避免自欺）

1. **开放词汇会幻觉。** 开放词表 grounding 可能在空处"看出"一个把手。第 1 轮已确认抓握误判成本不对称（漏判 vs 误判），开放词汇把误判来源从"隐变量估计"扩大到"语义感知"，风险更高。故必须**高精度门控 + 可弃权（abstain）**：宁可退回闭集/通用，不可自信地错。
2. **组合泛化 ≠ 组合执行。** 技能可乘性组合，不代表执行也乘性泛化；部件组合的动力学仍是新的。必须把"语义可组合"与"控制可泛化"分开验收。
3. **缓存会固化错误。** 一旦缓存了错误语义，它会在多个控制步里持续注入错误条件，把单帧 VLM 错误放大成系统性失败。缓存必须有**失效触发器 + 陈旧度度量**，而非纯 TTL。
4. **算力调度可能反噬。** 把算力堆到断点相位，如果断点识别错了，就在错误的地方烧预算；且尖峰分配会恶化 p99。必须有平滑与兜底。
5. **合规红线不变**：不利用评测端未声明语义、不硬编码任务分支、不从延迟/端口推断评测内部信息。开放词汇必须是模型能力，不是"读题猜任务"。

## 3. 研究问题（本轮新增）

- **Q6（开放词汇的物理接地）**：在只有语言 + 4 路 RGB、无深度真值的接口下，能否把"可夹边/把手/槽/盖/开口"作为**开放部件词表**检测出来，并直接供给抓握与插入，而不经过物体类别？
- **Q7（组合技能的可检索性）**：把任务 token 从 32 类闭集改为"动词×部件功能×关系"的组合后，未见任务能否被检索到**可执行**的已见技能组合？检索错误的代价与可弃权阈值如何定？
- **Q8（缓存语义的正确性与新鲜度）**：语义缓存何时有效？如何用场景变化/相位/置信度定义失效谓词，使"重算次数"与"陈旧导致的失败"同时可控？
- **Q9（延迟预算的最优分配）**：在恒定外部节拍 τ 与 N 端口共享后端下，如何把 anytime 算力分配到相位/帧，使期望成功率最大且 p99 ≤ τ？
- **Q10（开放度—延迟的可兑现前沿）**：固定延迟预算时，"增加开放词汇能力"能不能转化为成功率？Pareto 前沿在哪，拐点在哪？
- **Q11（可信度自证）**：如何让"内部算力随相位变化"在外部表现为**稳定节拍与良构动作**，从而通过官方延迟/规律性审计？

## 4. 设计原则（增量）

- **P7 开放部件优先于开放类别**：一切语义条件化以 part–affordance 为单位；类别只作检索先验，不作动作前提。
- **P8 可弃权优先于自信**：开放词汇模块必须能输出 `unknown` 并回退闭集/通用；高精度 > 高召回（延续 U6 的不对称成本观）。
- **P9 延迟是约束不是奖励**：在 τ 内最大化算力收益；外部节拍恒定，内部 anytime 可伸缩。
- **P10 缓存即记忆，必须可失效**：任何跨步复用的语义都带置信度与失效谓词，且错误可被下一帧证据推翻。
- **P11 开放度必须可测量**：每条 OOD 结论标注在"开放词表/组合"哪个轴上成立；不做笼统的"更泛化"叙事。

## 5. 与第 1 轮的关系

- **升级**：IP-01（SkillToken-MoE）→ IP-10 组合技能 token（开放词表、专家可复用）；IP-02（GraspVerify）→ 由 IP-09 开放部件供料，抓握判定获得未见物体的几何先验；IP-03（ChunkStitch）→ IP-12 延迟感知 chunk + 节拍整形；IP-06（代理评测）→ 增加"开放词汇/组合/OOD"切分与延迟轴。
- **保留**：IP-02 的保守介入准则、IP-03 的缝合与审计、IP-06 的六因子分解。
- **新增**：IP-09 OpenAffordance（开放部件/功能接地）、IP-10 CompositionalSkill、IP-11 SemanticCache、IP-12 ComputeScheduler、IP-13 RefParse（开放指代解析）、IP-14 QueueTail（多端口尾延迟与批处理）。
- **降级/暂存**：IP-05（姿态先验）、IP-07（双空间）继续 P2；IP-04（在线适配）因合规不确定暂不扩大。

## 6. 本轮最大风险（一句话）

**开放词汇 + 缓存 + 算力调度三者叠加会把"一次语义幻觉"变成"持续多步的系统性错误"：在延迟压力最大、最需要仔细看的未见物体场景，系统反而最可能缓存一个自信但错误的部件/功能假设并据此执行，且因缓存和节拍整形而难以及时纠正。**

## 7. 下一轮迭代计划

- **深化**：把 IP-09 的部件接地与 IP-11 的失效谓词联合训练（感知不确定度 → 缓存失效），把 IP-12 的预算分配从启发式升级为可学习的相位价值模型。
- **修剪预案**：若 E619（未见物体部件接地）与 E623（双环延迟）不能同时达标，则**先保延迟合规的闭集基线**，把开放词汇限制为"仅对目标物做一次性 grounding"（每 episode 一次，不进缓存高频路径）。
- **保留项**：IP-11（缓存）与 IP-12（节拍/预算）是任何形态都需要的工程地基，不砍。

## 0. 本轮结论摘要

**一句话路线**：第 1 轮的上限由"抓握隐变量不可信 + 语义条件是闭集"锁死；本轮用 **开放部件/功能接地（慢环）** 提供可泛化的物理条件，用 **组合技能 token + 语义缓存（摊销）** 把开放度变成可复用的执行条件，用 **节拍恒定的 anytime 算力调度（快环）** 把推理延迟从敌人变成预算。三层合成即 **UniBot-OPAL**。

**三条延续锚点（第 1 轮 teaser 榜实测，本轮作为设计约束）**：

| 证据 | 数值 | 本轮如何继续使用 |
|---|---|---|
| `step ≈ 1.337·succ + 0.09`，R²=0.9955 | 两指标近共线 | 仍只优化终态成功；延迟改善不直接计分 |
| 跨任务 Kendall τ 均值 0.064，oracle 33.96 vs 最佳单模型 29.70 | 技能近正交 | 组合技能 token 的目标是**让 oracle 空间在开放词表上可检索、可复用** |
| 任务内 `corr(时长,成功) ≈ −0.011`，episode 43.7–45.2 s | 快无红利 | **把延迟预算花满**：在 τ 内堆算力，而非追求更快；唯一硬约束是 p99 与平滑度 |

**本轮的战略转折**：第 1 轮把延迟当"工程成本"（越省越好）；本轮把它当"约束性预算"（**必须花完、绝不超支、外部恒定**）。这条转折直接来自"快无红利 + 延迟被审计"两条事实的交集，是本轮最反直觉、也最可能被忽略的可兑现点。

**合规红线（P5/P8/P11）**：单一 checkpoint、单一 API；开放词汇是**模型能力**而非读题硬编码；可弃权优先于自信；不利用评测端未声明语义；不做"从端口/延迟反推评测内部"的越界动作。

## 2. 创新点详述

### IP-09 · OpenAffordance 开放部件–功能接地（P0）

- **动机**：第 1 轮抓握隐变量依赖"物体随臂运动"的间接标签，在未见物体上整体漂移。开放世界的抓取/插入其实由**部件功能**决定（薄边可夹、把手可握、槽可插、盖可拧、开口可倒），而部件词表天生开放、跨类别复用。类别闭集是泛化失败的上游原因。
- **与现有方案的差异**：常见开放词汇工作是"检测更多物体类别"；本方案检测的是**功能部件**并用其驱动动作，物体类别只作检索先验。这使"未见物体"不再落入"最近旧类"，而是落入"最近旧部件功能"。
- **技术可行性**：中–高。接口给 4 路 RGB 与语言；可用开放词汇检测器 + 可提示分割器生成部件掩码，再由轻量 affordance 头输出"可夹/可插/可倒/可旋/可推"热图；无需深度真值（用单目几何 + EE 位姿近似）。
- **所需资源**：数据 = 官方 32 数据集自动伪标 + 少量人工抽检；算力 = 检测/分割用现成模型离线批跑；在线只跑小头 + 缓存。
- **落地步骤**：①定义部件/功能词表 `P × A`（≤30 个词，覆盖 32 任务）；②用 VLM 批量给数据打部件–功能伪标，人工抽检 5%；③训练 affordance 头（输入部件掩码 + 腕部帧）；④接 IP-02 的抓握判定与 IP-10 的技能检索；⑤做"闭集类别 vs 开放部件"在未见物体上的对照。
- **风险**：①**开放词汇幻觉**（空处看出把手）⇒ 高精度阈值 + 可弃权 + 多帧一致性；②部件词表设计偏差 ⇒ 用任务覆盖审计，词表是超参而非事实；③单目几何误差 ⇒ 只用相对几何，不硬算绝对深度。

### IP-10 · CompositionalSkill 组合技能 token（P0）

- **动机**：第 1 轮 32 类任务 token 在 OOD 指令上必然错配；而跨任务专长近正交（τ≈0.064）说明真正共享的是**技能因子**而非任务本身。
- **与现有方案的差异**：把"32 选 1 分类"换成"动词 × 部件功能 × 空间关系"的组合嵌入 `z_skill`，从技能原型库检索；组合空间乘性扩张，专家按因子复用（满足 P3"每专家≥2 任务"）。仍是单 checkpoint、单 API。
- **技术可行性**：高。语言侧用冻结文本编码器；因子伪标可从"任务名 + 物体/动作统计"得到；OOD 指令自然落到最近的因子组合。
- **所需资源**：算力 = 文本编码 + 原型检索，极小；训练 = 在 IP-01 骨架上改 token 头。
- **落地步骤**：①构建因子词表与原型库；②把 32 任务自动分解为因子组合并人工校验；③训练/微调组合 token 头；④OOD 指令检索 + 可弃权回退 `z_gen`；⑤oracle 路由 vs 真实路由的兑现率消融。
- **风险**：①组合语义正确但执行不泛化（见 §4 L10 的显式 caveat）⇒ 分开验收；②因子正交假设过强 ⇒ 保留交互项；③检索错配 ⇒ 低置信退回通用 token。

### IP-11 · SemanticCache 语义缓存与失效（P0）

- **动机**：开放词汇慢环若每控制步都跑，延迟与算力不可承受；但桌面场景在短时间尺度上高度稳定，语义可复用。
- **与现有方案的差异**：不是简单 TTL 缓存，而是**证据驱动的失效谓词**：指令变化、相位切换（进入抓握/对齐/插入）、光流能量超阈、置信度低、陈旧超限、或**抓握滑移信号**触发重算。缓存与 IP-02 联动，感知不确定度直接决定新鲜度需求。
- **技术可行性**：高（工程 + 轻量状态机）。
- **所需资源**：接口内状态，O(1)/端口；算力可忽略。
- **落地步骤**：①定义缓存条目（部件集合、技能 token、置信度、时间戳、视点摘要）；②实现失效谓词与重算预算；③测命中率–陈旧–成功三角；④与 IP-12 调度联动（重算帧优先获得预算）。
- **风险**：**缓存固化错误**（见 §4 L14）⇒ 失效谓词必须在"错误代价高"的相位（grasp/align/insert）收紧；提供"强制重算"兜底。

### IP-12 · ComputeScheduler 延迟预算与节拍整形（P0）

- **动机**：第 1 轮证明"快无红利"，而延迟被审计；因此正确目标是**在稳定节拍内花满预算**，尤其把算力堆到断点相位。开放词汇慢环引入可变延迟，必须与外部节拍解耦。
- **与现有方案的差异**：多数提交"固定 chunk + 固定推理"；本方案是 **anytime 计算 + 相位价值分配 + 固定外部节拍**：内部可伸缩（粗→精、专家数、分辨率、扩散步数），外部观察到的延迟保持平滑、可审计。
- **技术可行性**：中–高。需先用官方 client 复刻延迟语义与 chunk 执行（沿用第 1 轮 IP-03 步骤①）。
- **所需资源**：在线调度 <1 ms；无新数据。
- **落地步骤**：①测真实 per-step 延迟分布与 chunk 语义；②实现 anytime 预测器 `q̂(α)`（质量–算力曲线）；③实现相位价值权重（align/insert 高权，transport 低权）；④实现固定节拍整形器（早完成则对齐到节拍，晚则降级输出）；⑤导出延迟/jerk/降级审计。
- **风险**：①尖峰分配恶化 p99 ⇒ 平滑 + 硬 reservation；②相位识别错则在错处烧预算 ⇒ 低置信退回均匀分配；③整形器引入额外等待 ⇒ 与 N 端口吞吐联合优化（IP-14）。

### IP-13 · RefParse 开放指代解析（P1）

- **动机**：5 类泛化含"干扰物"与"未见物品"；语言常含属性/关系（"左边那个红色容器"），需在开放检测结果上选对目标，选错代价极高。
- **与现有方案的差异**：把"检测到就抓"改为**指代解析 + 歧义弃权**：按指令嵌入与空间关系给候选打分，margin 不足则弃权回退（如先做一次探索性重定位），不赌。
- **技术可行性**：中–高；可复用 IP-09 的检测与掩码。
- **所需资源**：轻量打分头 + 空间关系解析；算力小。
- **落地步骤**：①解析指令中的属性/关系；②在开放检测集合上打分；③margin 阈值 + 弃权策略；④干扰物场景 A/B。
- **风险**：弃权过多导致任务无法启动 ⇒ 弃权后必须有明确的探索动作，而非原地不动。

### IP-14 · QueueTail 多端口尾延迟与批处理（P1）

- **动机**：官方要求 N 个连续端口、每端口独立全流程、随机顺序；共享后端时，批处理省算力但抬高尾延迟，直接撞审计。
- **与现有方案的差异**：把并发当**排队系统**设计：EDF（最早 deadline 优先）+ 关键相位预留 + 传输相位可批处理；并对状态隔离做强制自检。
- **技术可行性**：高（系统工程）。
- **所需资源**：极小；需压测脚本。
- **落地步骤**：①建模 N 端口到达与服务；②EDF + 相位优先级队列；③批处理仅用于非关键相位；④N 端口 × 8 h 压测 + `reset()` 隔离断言。
- **风险**：优先级导致饥饿 ⇒ 设最大等待与降级；批处理抖动 ⇒ 小 batch + 超时即发。

## 3. 符号与定义（U13–U23）

| 符号 | 含义 |
|---|---|
| `P` | 开放部件词表（handle / rim / slot / lid / opening / neck / button / edge …），可扩展 |
| `A` | 功能集合（graspable / insertable / pourable / rotatable / pushable …） |
| `Q(ℓ,I_t)` | 开放部件–功能查询结果 |
| `z_skill` | 组合技能 token = 动词 ⊕ 部件功能 ⊕ 关系 |
| `χ` | 语义缓存条目 |
| `V(χ,o_t)` | 缓存有效性谓词 |
| `f_s, f_c` | 慢环语义率、快环控制率 |
| `α` | anytime 计算分配比例 ∈[0,1] |
| `q̂(α)` | 质量–算力曲线预测器 |
| `w_p` | 相位 p 的算力边际价值 |
| `L*` | 外部目标节拍（观测延迟均值） |
| `τ` | 每步延迟预算（p99 约束） |
| `δ` | 指代解析弃权 margin |
| `S(χ,o_t)` | 语义陈旧度 |

**定义 U13（开放部件–功能查询）** `Q(ℓ,I_t) = {(p_j,a_j,M_j,s_j)}_{j=1..m}`，`p_j∈P`、`a_j∈A`、`M_j` 为部件掩码、`s_j∈[0,1]` 为置信度；若 `max_j s_j < τ_sem` 则输出 `⊥`（弃权）。**不经过物体类别**。

**定义 U14（组合技能 token）** `z_skill = normalize(φ_v(verb)+φ_a(aff)+φ_r(rel))`；技能检索 `k* = argmax_k cos(z_skill, e_k)`，`e_k` 为技能原型；`z_skill` 允许落在训练任务原型之外（开放词表）。低相似度退回通用 token `z_gen`。

**定义 U15（语义缓存与有效性）** 缓存条目 `χ=(Q, ẑ_skill, t_0, c, v)`；有效性 `V(χ,o_t) = 1[ℓ 未变 ∧ flow(o_t)<λ_f ∧ c≥c_min ∧ t−t_0≤T_max ∧ ¬slip_t]`，其中 `slip_t` 来自 IP-02 的抓握滑移信号。失效即重算。

**定义 U16（双频环）** 语义更新率 `f_s ≪ f_c`；在缓存命中时，控制步延迟 `≤ τ_c` **与语义模型规模无关**。缓存未命中时以"有界陈旧"运行（不阻塞控制环）。

**定义 U17（anytime 计算）** `q(α)` 为质量随计算比例 `α` 的曲线，假设非降且分段凹；在线用 `q̂(α)` 预测，deadline 前择优输出。

**定义 U18（相位价值分配）** `w_p = ∂E[success]/∂α`；分配解 `α* = argmax Σ_p w_p·q̂(α_p)·n_p` s.t. `Σ cost(α_p) ≤ B` 且 `p99(L) ≤ τ`。

**定义 U19（外部节拍与整形）** 外部观测延迟序列满足 `|L_t − L*| ≤ ε` 且无突发；内部 anytime 计算被整形器藏在该节拍内，超时则降级（标记 `degraded`）。

**定义 U20（N 端口排队）** 服务容量 `C`、到达率 `N/T`；尾延迟上界由排队 + 批等待 + 服务时间组成；策略在 `p99 ≤ τ` 下最大化吞吐。

**定义 U21（开放指代解析）** 目标 `τ* = argmax_j sim(ℓ, j)`，`j` 遍历 `Q` 的候选；若 `sim_(1) − sim_(2) < δ` 则弃权并触发探索动作。

**定义 U22（语义陈旧度）** `S(χ,o_t)` 度量缓存语义与当前观测的偏离（视点/光流/遮挡摘要）；陈旧度越高，进入抓握/对齐/插入相位时越应强制重算。

**定义 U23（开放组合泛化分）** 在"未见过因子组合"上的成功率相对"已见组合"的保持率；与"仅闭集类别"基线对比，分离语义泛化与执行泛化。

```python
# ===== UniBot-OPAL：双频环 + 缓存 + 节拍恒定调度（单 checkpoint、单 API）=====
class UniBotOPAL:
    def __init__(self, ckpt, tau_ms=105, ports=range(8765, 8768), N=3):
        self.model   = SAGEBackbone(ckpt)          # 第1轮 IP-01/02/03 主干 + 专家
        self.grounder= OpenVocabGrounder()         # IP-09：慢环语义
        self.refparse= RefParser()                 # IP-13：开放指代解析
        self.skills  = CompositionalSkillLibrary() # IP-10：组合技能检索
        self.cache   = SemanticCache()             # IP-11：证据驱动失效
        self.sched   = ComputeScheduler(tau_ms)    # IP-12：预算分配 + 节拍整形
        self.tail    = TailScheduler(N, capacity=…) # IP-14：端口排队
        self.sessions = {}                          # 每端口独立状态（隔离）

    @property
    def metadata(self):
        # 与第1轮一致：obs_delta_indices / image_resize / control_space / token
        return self._metadata()

    def get_action(self, obs, port=None):
        s = self.sessions[port]
        # 1) 慢环：仅当缓存失效才重算；未命中不阻塞控制环
        if self.cache.invalid(obs, s):              # U15：含 slip / phase / flow / conf
            sem = self._slow_loop(obs, s)           # U13 + U21 + U14
            self.cache.update(sem, obs, s)
        sem = self.cache.get(s)                     # 可能带"有界陈旧"

        # 2) 预算分配：相位价值 + deadline，anytime
        alpha = self.sched.allocate(phase=sem.phase, cache_age=self.cache.age(s),
                                    backlog=self.tail.backlog(port), deadline=self.sched.tau)
        z = sem.z_skill if sem.conf >= self.tau_sem else GENERIC_TOKEN  # U14 可弃权
        a = self.model.act(obs, z, sem.phase, alpha) # 快环：延迟与语义规模解耦

        # 3) 缝合 + 外部节拍整形（合规优先）
        a = self.stitch(a, s.last_action)            # U7（第1轮）
        a = self.sched.pace(a, s, self.tail)         # U19：恒定节拍 / 超时降级
        s.last_action = a[-1]
        return self.pack(a)

    def _slow_loop(self, obs, s):
        Q = self.grounder.query(obs["observation.language"], obs["images"], P, A)  # U13
        if Q.is_empty():                             # 幻觉/无部件 → 弃权
            return SemanticState.empty(phase=s.phase)
        tgt = self.refparse.select(obs["observation.language"], Q, delta=0.15)     # U21
        z = self.skills.retrieve(obs["observation.language"], tgt)                 # U14
        return SemanticState(Q=Q, z_skill=z, conf=tgt.conf, phase=self.phase_of(obs))
```

```python
# ===== IP-09：开放部件–功能接地（慢环，可 anytime）=====
class OpenVocabGrounder:
    def query(self, instruction, images, P, A):
        prompts = compose_prompts(instruction, P, A)   # "the graspable rim of ...", "slot", ...

# ===== IP-10：组合技能检索（开放词表，可弃权）=====
class CompositionalSkillLibrary:
    def retrieve(self, instruction, target):
        z = normalize(textenc(instruction) + self.aff_embed(target.affordance)
                      + self.rel_embed(target.relation))
        k, sim = self.nearest_prototype(z)
        return SkillToken(z, k, conf=sim) if sim >= self.tau_skill else SkillToken.generic()

# ===== IP-11：证据驱动缓存失效（不是纯 TTL）=====
class SemanticCache:
    def invalid(self, obs, s):
        return (s.instruction_changed or s.phase in {GRASP, ALIGN, INSERT}
                or self.flow(obs) > self.lambda_f or s.sem_conf < self.c_min
                or self.age(s) > self.T_max or self.grasp_slip(obs))   # U15 / 与 IP-02 联动

# ===== IP-12：anytime 预算分配 + 节拍整形 =====
class ComputeScheduler:
    def allocate(self, phase, cache_age, backlog, deadline):
        w = self.phase_value(phase)                    # U18：align/insert 高权
        alpha = self.waterfill(w, remaining_budget(deadline, backlog))  # 凹曲线贪心
        return clamp(alpha, 0.0, 1.0)

    def pace(self, a, s, tail):
        # 外部节拍恒定：早完成对齐到 L*；晚于 deadline 则降级输出并标记
        if tail.behind():  return self.degrade(a, s)   # U19：安全延拓 + 减速标记
        return self.align_to_beat(a, s, tail.L_star)
```

## 5. 推导（引理 L8–L14）

**引理 L8（缓存摊销界）** 设慢环单次语义成本 `C_s`、控制率 `f_c`、缓存命中率 `h`，则每控制步平均语义成本 `C̄ = (1−h)·C_s·f_s/f_c`（按重算率折算）。当 `h ≥ 1 − τ_c·f_c/(C_s·f_s)` 时，语义成本不挤占控制预算。teaser 榜已给出"快无红利"，故目标不是最小化 `C̄`，而是把省下的预算**再投到断点相位的 `α`**。∎

**引理 L9（双环延迟分离）** 若缓存未命中时不阻塞控制环、仅以有界陈旧 `Δ` 继续，则控制步 p99 ≤ `τ_c` 与语义模型规模无关；语义慢环的延迟只通过"陈旧度 `Δ`"影响成功率。因此 `∂success/∂(semantic latency)` 在有界 `Δ` 内为 0，超过 `Δ` 才转负。∎

**引理 L10（组合空间乘性扩张，附执行保留）** 若技能分解为 `V×A×R` 三因子，则语义上可覆盖的任务数为 `O(|V|·|A|·|R|)`，而闭集仅 32。若每因子在训练中有 ≥n 个覆盖，则任一未见组合的**语义检索**误差受因子嵌入误差三角不等式约束；但**执行**泛化不被蕴含，须由 E632 单独测量。∎

**引理 L11（预算分配的凹–凸判别）** 若 `q(α)` 在相位内凹，则总预算下贪心 water-filling 最优；若存在阈值效应（凸），贪心次优，应在关键相位**全有或全无**。因此本设计采用"相位内凹 + 相位间阈值"的混合规则，并用 E625 验证。∎

**引理 L12（指代误选的不对称成本）** 令正确目标增益 `G`、误选损失 `L`（可破坏场景）、正确概率 `p`，期望效用 `p·G − (1−p)·L`；弃权阈值为 `p < L/(G+L)`。因 `L ≫ G`，最优策略是**高精度 + 弃权**，而非最大化识别率。∎

**引理 L13（批处理尾延迟界）** 批大小 `B` 引入等待 ≤ `(B−1)/μ`（`μ` 为服务率），故 `p99(L) ≤ queue_p99 + (B−1)/μ + service_p99`。要满足 `p99 ≤ τ`，要么减小 `B`，要么对关键相位复制后端（降 `queue_p99`）。这就把"省算力"与"过审计"变成可解的约束优化。∎

**引理 L14（幻觉的缓存放大）** 若单次语义帧假阳性率 `α`，缓存平均存活 `T_eff` 个控制步，则一段 episode 内"至少出现一次持续错误语义"的概率约 `1−(1−α)^{R}`（`R` 为重算次数），但**每次错误的持续代价 ∝ T_eff**。故缓存降低幻觉**频率**（`R` 降），却提高单次幻觉的**持续性**（`T_eff` 升）。必须在高代价相位收紧失效谓词，使 `T_eff` 在 grasp/align/insert 上趋于 1。∎

## 6. 复杂度与延迟预算

> 下表为**设计目标**，非实测事实；所有数值须由 E623/E624/E628 在官方 client 复刻环境中测得后回填。

| 组件 | 环路 | 时间/步（目标） | 空间 | 正确性锚 |
|---|---|---|---|---|
| 开放部件 grounding（IP-09） | 慢环，仅 miss | 40–200 ms / miss，命中摊销后 ~ms 级 | 中（离线可批） | U13 / L8 |
| 指代解析（IP-13） | 慢环 | ≤10 ms | 小 | U21 / L12 |
| 组合技能检索（IP-10） | 慢环/快环 | ≤2 ms | 小 | U14 / L10 |
| 语义缓存检查（IP-11） | 每步 | <1 ms | O(1)/端口 | U15 / L14 |
| 主干 + 专家（IP-01/02） | 快环 | 35–70 ms | 1×权重（N 端口共享） | U1 / L9 |
| 缝合 + 限幅（IP-03） | 快环 | <1 ms | O(1) | U7 |
| 预算分配 + 节拍整形（IP-12） | 每步 | <1 ms | O(1) | U18/U19 / L11 |
| 端口排队（IP-14） | 后端 | 调度 <1 ms，等待受控 | O(N) | U20 / L13 |
| 训练：部件伪标 + 因子分解 | 离线 | 32 数据集 × ~1000 eps | 中 | U13/U14 |
| 训练：组合 token 微调 | 离线 | 8×A100 × 1–2 天 | 中 | L10 |

**硬约束（沿用官方 README）**：连续端口 `8765…8765+N−1`；每端口独立全流程；`reset()` 与历史状态不得跨端口串扰；延迟与动作规律性被审计。⇒ 部署仍是**共享后端 + N 个轻量前端**，但本轮新增**常外部节拍 + EDF 端口调度**，把"内部 anytime"与"外部合规"分离。

## 9. 风险登记册与剪枝预案

| 风险 | 概率 | 影响 | 对冲 |
|---|---|---|---|
| **语义幻觉被缓存放大** | 中高 | 高 | 高精度门控 + 可弃权 + 高代价相位 `T_eff→1` + 多帧一致性 |
| **开放度换来延迟超标/抖动** | 中 | 高（判不可信） | 双环解耦 + 常外部节拍 + p99 硬约束 + 降级兜底 |
| **组合泛化只停在语义层** | 中高 | 中 | E632 单独验收；不把语义可组合当执行可组合 |
| **缓存陈旧致系统性失败** | 中 | 高 | 证据驱动失效（含 slip/flow/phase）+ 强制重算 + 陈旧度门控 |
| **算力分配尖峰恶化 p99** | 中 | 中 | 平滑 + 关键相位预留 + EDF（IP-14） |
| **指代选错破坏场景** | 中 | 高 | 高精度 + 弃权 + 探索动作（不原地不动） |
| **合规**：开放词汇被判"读题硬编码" | 中 | 高 | 开放词汇是模型能力；提交前书面确认；准备闭集降级形态 |
| **代理评测失真**（沿用第 1 轮） | 中 | 中高 | E601 优先；\|r\|<0.3 触发剪枝 |

**剪枝预案**：
- **必保**：IP-11（缓存）、IP-12（节拍/预算）、第 1 轮 IP-02/IP-03（机制正确性 + 合规地基）。
- **优先深化**：IP-09/IP-10（唯一把"开放词汇"转成可兑现泛化的路径），但须过 E630 的"开放度兑现"闸门。
- **条件推进**：IP-13（依赖 E628）、IP-14（依赖 N 端口压测结果）。
- **暂存**：IP-05、IP-07、IP-04（合规未决）。
