# 第 3 轮迭代（灵感循环 v3：「中间件」×「视觉编码器」）——把 RHPV-D 从“策略技巧”下沉为“感知-服务反射弧”

> 承接第 2 轮的 UIP-01′~15。本轮不再往“策略层”堆新技巧，而是把上一轮旗舰**往下沉**：它必须活在**中间件**里（在评测端每次 `get_action` 之间保状态、控时序、守隔离），并且靠**视觉编码器**提供两个廉价信号（子目标进度、外部扰动惊讶）。同时本轮先做一次证据审计：上一轮有两个默认假设可能把方向带偏，必须当场纠正，否则后面所有实验都在错误的靶子上刷分。

**三个当场纠正：**

1. **UIP-13 ACS 作废/改写。** `action_chunk_size` 不可在运行期变，也不能少返回几步；所谓“按阶段动态选 k”只能退化为**握手前离线选一个全局 T_a**，或在固定块内做动作整形（但拿不到新观测）。因此“实时性”的正解不是“变块长”，而是“**选对固定块长 + 把服务层排队与载荷压稳**”。
2. **榜单 fixture 不能当证据。** 上一轮“步骤分安全网”的紧迫性来自规则文本（B 级）而非榜单；本轮保留该机制，但**理由改成“成功率优先”**：检测“进度被撤回→重做”首先救的是成功率，其次才可能救步骤分。这样无论真实计分是“部分分”还是“与成功率高度仿射”，机制都站得住。
3. **不要把中间件做成“更多框架”。** 评测链路是 websocket + msgpack + JPEG，任何额外的 ROS/DDS/序列化层都只会加延迟。中间件的价值是**更少的拷贝、更严的隔离、更稳的排队**，不是更重的栈。

## 1. 直觉解释（先直觉，后定义）

**中间件：不是“模型里的模型”，而是“模型与评测端之间的反射弧”。** 直觉上，策略网络像大脑皮层，决定“抓哪里、怎么放”；中间件像脊髓，决定“这一次观测属于哪台机器人、什么时候把动作块交出去、上一块说完成了的子目标下一帧是否还算数”。在远程 API 里，评测端执行完整动作块后才再来要下一块，所以中间件**不能凭空创造观测**；它只能在**块边界**做三件事：保住每端口状态、把延迟与抖动压平、把“完成/被撤回/失败”的判断接力下去。它的力量来自“不改模型也能改系统行为”，它的边界也来自“看不到块内”。

**视觉编码器：物理世界进入策略的唯一门，也是延迟与捷径的共同源头。** 直觉上，5 条泛化轴（未见物品、位置、干扰物、背景、人为干扰）都不是先打到动作头，而是先打到编码器；编码器若把“桌布颜色/背景纹理”当成动作线索，动作头再强也会在换背景时崩。与此同时，4 路相机 × 时间堆叠意味着编码器是载荷与算力的大头：每多一帧就多一张 JPEG、多一份 token。于是编码器同时是**鲁棒性杠杆**和**实时性杠杆**——这正是本轮把两个灵感词放在一起的原因。

## 2. 严谨定义

**定义 1（中间件）**：对每个端口 `p`，中间件是一个有状态转导器 `M_p = (S_p, δ_p, π_p)`，把观测序列 `o_{t_0}, o_{t_1}, …`（只在块边界到达）映射为动作块序列 `A_{t_i} ∈ R^{T_a×d}`，并满足：① `S_p` 在端口间不相交；② `reset(p)` 只清 `S_p`；③ 对任意 `p≠q`，`M_p` 的输出不依赖 `S_q`。端到端延迟分解为
`L = t_cap + t_net + t_dec + t_pre + t_enc + t_head + t_post + t_queue`。
中间件可直接控制 `t_dec,t_pre,t_post,t_queue`，并通过**每视角分辨率/堆叠帧数**间接控制 `t_enc`；不能控制评测端的 `t_cap,t_net`。可信度约束写成：`P(L > L_max) ≤ ε`、`Var(L) ≤ V_max`，且动作序列通过统计规律性检查。

**定义 2（视觉编码器与适配）**：`E_θ: X → R^{n×d}` 把图像映射为 token/特征；低秩适配 `θ = θ_0 + Δ`，`Δ = U V^T`，`rank(Δ)=r ≪ d`。对保持任务标签的**反事实变换** `C`（换背景、光度扰动、换视角、时间相邻帧），定义** nuisance 敏感度**
`N(E) = E_{o∼D, o_cf∼C(o)} ‖φ(E(o)) − φ(E(o_cf))‖²`，
其中 `φ` 是动作读出或任务探针。`N` 越大，说明编码器越依赖与任务无关的捷径。

**定义 3（每视角感知预算 PVEB）**：为 4 路视角 `v` 选分辨率 `r_v` 与堆叠帧数 `m_v`。像素/载荷成本 `C = Σ_v r_v m_v`，token 数近似 `K = Σ_v ⌈h_v/p⌉⌈w_v/p⌉ m_v`（`p` 为 patch 边长）。在 `C ≤ C_max, K ≤ K_max, P(L>L_max)≤ε` 下最大化期望成功率。它是“带延迟约束的背包分配”，不是单一超参。

**定义 4（固定块长决策）**：由于 `T_a` 握手后不可变，把“自适应块长”改写为
`T_a* = argmax_{T_a ∈ {1,2,4,8,15,30}} E[score | T_a, 服务层, 编码器预算]`。
块内只能做动作整形（平滑、限幅、末段减速），不能重观测；最坏反应延迟 = `T_a` 个控制步。

**定义 5（进度账本与两个信号）**：子目标 `g_0…g_{m-1}` 对应计分步。块边界得到编码器特征 `f_t = E(o_t)` 后：
- **监督探针** `p_ψ(f_t) → Δ^{K}` 给出 `{未开始,进行中,完成,被撤回}` 的后验；
- **潜在惊讶** `s_t = d(f_t, g_φ(f_{t-1}, a_{t-1}))`（`d` 用马氏距离，`g_φ` 是共享骨干上的小预测头）度量“世界是否按我的动作预期变化”。
两者共同驱动 RHPV-D 的 `done/regressed/fail` 状态机：`s_t` 高且探针说“完成度回退”才判 `regressed`，避免把正常接触抖动误判为人为撤回。

## 3. 瓶颈假设（更新）

- **H1（服务层容量，最高杠杆）**：在 N=3、控制 30 Hz、`T_a=8` 时，每端口约 267 ms 一次请求；若单次推理 `s_0≈150 ms`，单后端串行利用率 `3×150/267≈1.69>1`，队列必然爆炸。共享模型要么把 `s_0` 压到 **<89 ms**，要么把 `T_a` 提到 ≥15，要么用 3 份独立模型。**批处理只在端口相位对齐时有明显收益；相位错开时，攒批要等接近一个周期，收益被等待吃掉。**
- **H2（固定块长）**：`T_a` 是全局折中：小 `T_a` 提高反应性但抬高请求率/载荷；大 `T_a` 降低调用次数但增加开环暴露。存在任务相关的内点最优，不能运行期切换。
- **H3（编码器鲁棒性）**：OOD 失败主要来自 nuisance 捷径，而非动作头容量；低秩适配 + 反事实一致性可用**无标签**信号选择适配强度。合成实验显示训练期一致性惩罚可把 OOD 成功从 0.28 提到 0.50（D 级，仅机制）。
- **H4（探针可替代外部 VLM）**：冻结编码器特征里已含足够子目标信息；小探针/小预测头即可做进度验证，避免“外部大模型=非单模型”的合规风险。
- **H5（计分世界二象性）**：真实计分可能是“部分分”（规则文本支持），也可能与成功率高度仿射（fixture 呈现）。**稳健机制必须在两种世界都靠成功率站得住**；只在一个世界有效的“刷步骤分”技巧应降级。

## 5. 本轮最大风险

**一句话**：中间件与编码器的优化都发生在“评测端可见性”的边缘，若没有先做端到端延迟-成功率联合测量，很容易把“更低的延迟/更小的 token”误当成“更高的排名”，而真正的失败仍来自视觉编码器的分布外捷径与固定 `T_a` 的开环暴露。

## 1. 服务层旗舰：UIP-16 · MW-Spine

### 1.1 为什么参考实现不够

A 级证据：`PolicyService._on_connection` 在一个连接内用 `async for` 顺序处理请求，且 `route(request)` 是同步调用（`policy/web_policy.py:291-306`）。这意味着：

- 同一个 `PolicyService` 实例**不会并发**处理多个客户端；
- 若把重模型放在事件循环里，任何一次推理都会阻塞该实例；
- README §5 的“Approach 2（共享一个模型）”把并发与状态隔离的责任明确留给选手。

因此，若 N=3 且每端口一个进程、各加载一份模型，最稳但显存×3；若共享一份模型，必须自建**异步调度 + 每端口会话隔离**。这不是“加框架”，而是补上参考实现故意留白的一层。

### 1.2 架构

```text
port 8765 ─┐
port 8766 ─┼─> [ thin websocket endpoint ] ─> [ per-port SessionStore ]
port 8767 ─┘         (decode/resize)                (state, history, ledger)
                              │
                              v
                    [ deadline-aware scheduler ]
                              │  (batch only if phase-aligned / util high)
                              v
                    [ inference worker(s) ] ─> E_θ, policy, probes
                              │
                              v
                    [ postprocess / governor / token check ] ─> reply
```

要点：

1. **每端口一个 `Session`**：`obs` 历史、子目标账本、探针状态、`reset` 版本号全部按 `port_id` 分区；推理 worker 只接收不可变的 `SessionView`，不持有跨端口可变状态。
2. **调度器看“截止时间”而非只看 FIFO**：每个请求带 `deadline = arrival + L_max`；攒批窗口不得超过最早请求的剩余预算。
3. **批处理是条件性的**：只有端口相位对齐（请求几乎同时到）或利用率高时才攒批；相位错开时攒批会白等一个周期，反而抬高 p95。
4. **背压**：队列长度超过阈值时，优先保证“每端口至少一次及时响应”，而不是无限攒批。
5. **可信度工程**：预热、CUDA Graph、预分配 pinned buffer、避免推理路径上的 GC、固定线程亲和；返回动作做轻量平滑与限幅（UIP-15）。

### 1.3 排队机制检验（D 级，合成）

假设：N=3，控制 30 Hz，单次服务 `s(B)=150+40(B−1)` ms，deadline 500 ms，持续 600 s。结果（`exp/r3_middleware_sim.json`）：

| `T_a` | 每端口周期 | 串行利用率 | 独立后端 p95 | 错开相位·串行 p95 | 对齐相位·串行 p95 | 对齐·batch(10 ms) p95 |
|---:|---:|---:|---:|---:|---:|---:|
| 8 | 267 ms | **1.687** | 150 ms | 391.9 s（不稳定） | 392.1 s（不稳定） | 230 ms |
| 15 | 500 ms | 0.900 | 150 ms | 150 ms | 448 ms | 230 ms |
| 30 | 1000 ms | 0.450 | 150 ms | 150 ms | 448 ms | 230 ms |

**结论：**

- `T_a=8` 时单后端串行**必然过载**（利用率>1）；要共享一份模型，必须把 `s_0` 压到 **< 89 ms**（`1000×8/30/3`），否则只能 3 份独立模型或把 `T_a` 提到 ≥15。
- 相位对齐时串行 p95 会到 448 ms（3 个请求同时到、串行 150 ms×3）；10 ms 攒批可降到 230 ms。
- 相位错开时串行反而没有排队（请求间隔 167 ms > 150 ms），攒批收益很小；**不要盲目批处理**。
- 这条结论直接连到 UIP-17：**降低每视角编码成本 = 降低 `s_0` = 让小 `T_a` 从不可行变可行**。服务层与编码器不是两件事。

## 2. UIP-21 · T_a-Profiler（替代 UIP-13）

### 2.1 纠正

A 级证据：`ExampleEnv.step` 校验 `action[key].shape != (self.action_chunk_size, ...)`（`example/example_env.py:164`）。因此：

- **不能**“声明 K_MAX、每次返回 ≤K 步”；
- **不能**“按阶段动态改块长”；
- 只能握手时定一个全局 `T_a`，每次返回完整 `T_a` 步。

### 2.2 决策

```text
T_a* = argmax_{T_a ∈ {1,2,4,8,15,30}}  E[score | T_a, 服务层, 感知预算]
s.t.  P(L > L_max) ≤ ε,  action_regularity_ok
```

离线流程：

1. 在 32 个公开数据集上回放“每 `T_a` 步才重观测”的闭环，测成功率衰减；
2. 在真实服务层上压测每 `T_a` 的 p50/p95/超时率；
3. 用 Gazebo（UIP-11）或数据回放估“开环暴露”带来的失败率；
4. 取帕累托前沿上综合分最高者，写进 `metadata`。

### 2.3 块内整形（不能重观测）

固定块内仍可做三件事，且不违反形状校验：

- **动作平滑/限幅**：避免统计规律性异常（UIP-15）；
- **末段减速**：接触密集步（插网线/合盖/拉链）在块末降低速度，降低“盲撞”；
- **保持位**：若探针在块边界已判定“完成”，下一块前几步可保持当前位姿，等待下一帧确认，而不是继续大幅运动。

这不是“自适应块长”，而是“固定块长 + 块内保守化”。

## 3. 感知层旗舰：UIP-17 · PVEB（Per-View Encoding Budget）

### 3.1 形式化

对视角 `v ∈ {head_L, head_R, wrist_L, wrist_R}` 选 `(r_v, m_v)`：

```text
max_{r_v,m_v}  E[success]
s.t.  Σ_v r_v m_v ≤ C_max                 (像素/载荷预算)
      Σ_v tokens(r_v) · m_v ≤ K_max        (编码器 token 预算)
      P(L > L_max) ≤ ε                     (延迟尾约束)
```

其中 `tokens(r) ≈ ⌈h/p⌉⌈w/p⌉`，`p` 为 patch 边长。因为 `p` 在分子分母中约掉，**token 缩减比例 ≈ 帧数缩减 × 像素缩减**，与具体 patch 大小无关。

### 3.2 一个可检验的预算假设

| 视角 | 原生 | 候选缩放 | 堆叠帧 | 理由 |
|---|---|---|---|---|
| head_L / head_R | 480×640 | 240×320 | 1 | 全局布局、物体是否存在；变化慢 |
| wrist_L / wrist_R | 480×640 | 240×320 或 320×240 | 2 | 接触细节；变化快，但只需短历史 |

算例（仅说明量级）：基线 4 视角×4 帧=16 帧，480×640，patch=14 → `35×46=1610` token/帧，共 **25,760** token；候选 6 帧、240×320 → `18×23=414` token/帧，共 **2,484** token，约 **10.4×** 缩减；像素从 4.9M 降到 0.46M（约 10.7×）。这既是延迟收益，也是带宽收益。

**风险**：拉链、插网线、拧盖等细接触任务可能依赖腕部高分辨率；必须按任务做消融，不能一刀切。E203 就是找每任务的帕累托点。

### 3.3 编解码一致性（CCT，作为 17 的训练侧子项）

A 级证据：上线图像是 **JPEG q95、4:4:4**，且评测端先 `cv2.resize` 再发（README §2 + `web_policy.py`）。公开数据是 AV1。训练/部署存在两种不一致：

1. **编解码**：AV1 解码帧 vs JPEG 块效应；
2. **缩放**：训练原生 480×640 vs 上线缩小后的插值纹理。

最小修复：在训练数据管线中**按部署链路做增强**——先缩放到目标分辨率，再以 q95/4:4:4 做 JPEG 往返（可随机 85–95 提升鲁棒性），再送编码器。成本极低，且直接对准“视觉编码器输入分布”而不是动作头。

## 4. UIP-18 · CV-ANCHOR（跨视角反事实编码器适配）

### 4.1 机制

冻结预训练编码器 `E_{θ0}`，只训练低秩适配 `Δ=UV^T` 与小动作读出/探针；损失：

```text
L = L_action + λ_cv · L_consistency + λ_reg · ||Δ||²
```

`L_consistency` 的三种可用配对：

- **跨视角**：head_L 与 head_R 是同一场景的两个视角；约束**任务探针输出**一致（不是原始特征逐像素一致）；
- **时间相邻**：同一 episode 的 `t` 与 `t−1`，动作变化很小时，任务相关探针应稳定；
- **光度/背景反事实**：颜色抖动、局部遮挡、背景替换（若可分割）；约束探针不变。

`λ_cv` 与秩 `r` **不用 OOD 标签选**，而用无标签一致性分数在留出 episode 上选：

```text
CV(E) = E_{o,o_cf} || p_ψ(E(o)) − p_ψ(E(o_cf)) ||²
```

### 4.2 已有合成机制证据（D 级，不可当机器人结论）

`exp/vision_loop_sim.py` / `vision_loop_results.json`（合成线性模型，隔离“ID 捷径 vs OOD 泛化”）：

| 选择器 | ID 成功 | OOD 成功 | 说明 |
|---|---:|---:|---|
| frozen | 0.900 | 0.300 | 不适配 |
| ID-val 选强度 | 0.997 | 0.283 | ID 刷高、OOD 更差（捷径） |
| CV-only | 0.900 | 0.300 | 退化到 frozen（一致性无梯度时不选） |
| CV-ANCHOR (μ=1) | 0.983 | **0.342** | 无标签一致性把强度拉回安全区 |
| 训练期 CV 惩罚 (cv_pen=10) | 0.983 | **0.503** | 训练时加一致性惩罚收益最大 |

**读法**：合成模型明确显示“ID 验证会选到更强捷径”，而一致性信号能把 OOD 拉回来；但这是线性合成模型，真实 VLA 上的增益必须用 E205 重测。**不要把 0.503 当预期值**。

### 4.3 算法

```python
# 冻结 E，训练 adapter + probe；用无标签一致性选强度
for step in range(T):
    o, o_cf, a = sample_pair(batch)          # 跨视角/时间/光度
    f, f_cf = E(o), E(o_cf)                  # 共享冻结主干 + adapter
    loss = action_loss(f, a) + lam_cv * probe_consistency(f, f_cf)
    loss += lam_reg * adapter_norm()
update(adapter, probe)
# 选择：在留出 episode 上扫 lam_cv/rank，取 CV 分数最低且 ID 不崩者
```

### 4.4 真实数据上的注意事项

- head_L/head_R 是两台相机，不是严格配准的立体对；一致性只能施加在**任务级探针**上，不能做像素级对齐。
- wrist 视角在接触时会剧烈变化，时间一致性窗口要短，且动作变化要小。
- 背景替换若做不好会改变任务语义（例如“白色桌面”本身是任务线索）；优先用光度/视角/时间配对，背景替换放最后。

## 5. UIP-19 · SPP（子目标进度探针）

### 5.1 机制

在冻结编码器特征 `f_t` 上挂轻量头（2 层 MLP 或多标签头），对每个计分步输出四态后验：

```text
p_ψ(f_t) ∈ Δ^4,  状态 = {not_started, ongoing, done, regressed}
```

标签来源（弱监督，按成本排序）：

1. `scoring_points` 文本 → 每个子目标一个“可观测谓词”；
2. 数据集 state/action 分段 → 自动对齐“开始/结束”时间段；
3. 32 任务各 2–5 个子目标，人工抽检少量片段校准；
4. Gazebo DRF（UIP-12）生成的“撤回→恢复”三元组补 `regressed` 类。

### 5.2 回归检测（与 LSM 联合）

```python
def verify(f_t, f_prev, a_prev, g, ledger):
    s = surprise(f_t, f_prev, a_prev)          # UIP-20
    p = probe(f_t)[g]                          # SPP 四态后验
    if p[done] > 0.7 and ledger[g] != DONE:
        ledger[g] = DONE; return ADVANCE
    if ledger[g] == DONE and p[done] < 0.4 and s > tau_s:
        ledger[g] = REGRESSED; return REDO      # 只有“完成度回退 + 惊讶高”才重做
    if p[fail] > 0.6:
        ledger[g] = FAIL; return RETRY
    return CONTINUE
```

关键：**不要只靠单帧分类器判 `regressed`**。单帧探针会把“手挡住物体”误判成“物体被拿走”；必须叠加时序（HMM/滑动窗口）与惊讶门控。

### 5.3 合规

- 探针与适配器共享同一条冻结骨干，不引入第二个大模型；不调用外部 VLM。
- 探针只在策略进程内做前向，不增加网络往返。
- 输出只用于内部状态机，不改变接口形状。

## 6. UIP-20 · LSM（潜在惊讶监控）

### 6.1 定义

```text
f_t      = E(o_t)                         # 编码器特征（建议用 head 视角做全局）
f̂_t      = g_φ(f_{t−1}, a_{t−1})          # 共享骨干上的小预测头
s_t      = (f_t − f̂_t)^T Σ^{-1} (f_t − f̂_t)   # 马氏距离
```

`Σ` 在**无干扰**数据上估计；阈值 `τ_s` 取干净数据 99 分位。`s_t` 高表示“世界没有按我的动作预期变化”，可能是外部干扰，也可能是接触/遮挡/相机运动。

### 6.2 用法

- **作为门控**：`s_t > τ_s` 时才让 SPP 复核当前子目标，避免每帧都跑完整验证；
- **作为撤回证据**：若 `s_t` 高且 SPP 显示 `done→not_done`，判 `regressed`；
- **作为伪标签**：Gazebo/真机采集中，`s_t` 高的片段优先人工标注，降低标注成本。

### 6.3 注意

- wrist 视角在接触密集步天然高惊讶；全局干扰检测用 head，接触验证用 wrist + 动作上下文；
- 相机自动曝光/白平衡会造成全局惊讶；`Σ` 要按场景/光照分层，或先做光度归一化；
- 预测头必须与主策略同骨干/同进程，避免“第二模型”合规争议。

## 7. RHPV-D v3：在中间件里跑的控制律

```python
class PARM:                      # UIP-16 + 01′ + 19 + 20 + 15 + 21
    def __init__(self, policy, encoder, probe, predictor, K=T_A, ...):
        self.sessions = {}       # port_id -> Session（严格隔离）

    def reset(self, port_id):
        self.sessions[port_id] = Session()

    def get_action(self, port_id, obs):
        s = self.sessions[port_id]
        f = self.encoder.encode(obs)
        s.surprise = self.predictor.surprise(f, s.prev_f, s.prev_a)
        st = self.probe.verify(f, s.surprise, s.g, s.ledger)
        if st == "advance":   s.ledger[s.g] = DONE; s.g += 1
        elif st == "redo":    s.redo += 1            # 被撤回：重做同一子目标
        elif st == "retry":   s.retry += 1
        A = self.policy.get_action(obs, s.g)         # 固定返回 T_a 步
        A = self.governor.shape(A, s)                # 平滑/限幅/末段减速/预算
        s.prev_f, s.prev_a = f, summarize(A)
        return A                                     # 形状严格 == (T_a, ...)
```

**边界**：只能在块边界重观测，最坏反应延迟 = `T_a` 控制步；因此 `T_a` 的选择（UIP-21）直接决定“撤回检测”的时间分辨率。

## 10. 合规与风险（v3 重点）

- **单模型**：适配器/探针/预测头全部共享同一条骨干；不调用外部 VLM；不训练 32 个独立模型。
- **接口红线**：动作形状严格 `(T_a, ...)`、dtype `float32`、键集合精确、token 每步携带；**不要返回变长块**。
- **端口隔离**：`SessionStore` 按 `port_id` 分区；`reset` 只清本端口；推理 worker 不持有跨端口可变状态。
- **可信度**：预热、固定线程、避免 GC、动作平滑；不要用“随机抖动/异常动作”博取偶然成功。
- **证据纪律**：fixture 不是榜单；合成不是真机；Gazebo 判分只作结构裁判。
- **PVEB 风险**：降分辨率可能伤细接触任务；必须按任务选预算，不能全局一刀切。
- **CV-ANCHOR 风险**：跨视角一致性可能把“视角差异”误当 nuisance；只在任务探针层做一致性，不做像素级。
- **LSM 风险**：相机运动/光照会造成假惊讶；用 head 全局 + 分层校准，阈值宁高勿低。

## 11. 本轮最大风险 & 押注

**一句话**：若把“中间件更快/编码器更小”本身当作排名收益，而不先证明它们在真实评测链路上同时改善成功率与可信度，就会陷入“优化了仪表盘、没优化成绩”的伪进展。

**→ 押注：UIP-16（MW-Spine）× UIP-17（PVEB）× UIP-19/20（SPP+LSM）组成的 PARM 闭环**——它把上一轮的 RHPV-D 从“策略层技巧”变成**服务层可托管、编码器可验证**的反射弧；先用 E201/E202/E203 证明延迟-成功率联合收益，再用 E205/E206/E207 证明感知信号真的能检出“进度被撤回”，最后才谈刷分。
