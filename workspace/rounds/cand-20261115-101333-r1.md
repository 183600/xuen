# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配多模态交互消歧」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「需求洞察」×「技术路线图」）

> R69 把不确定性一分为二，并第一次教会闭环「问」：aleatoric 收紧，epistemic 用看/问/触去消解。但 R69 有两个从未写进证书的默认前提：
> **(a) 所有歧义等价**——U_epi 用模态熵计价，等于假设「选错哪个模态」代价相同；
> **(b) 所有歧义都值得在当下问**——它没有跨 episode 的记忆，也没有「有些问题再问也问不出来」的能力模型。
>
> 于是 R69 的最大风险只被回应了一半：它担心「模态权重不可信 → 自信地追问一个幻影」；更常见的另一半是「这类歧义每个 episode 都复发，而现有传感器/技能永远消解不了 → 系统 forever ask」。前者是问错，后者是问到死。
>
> 本轮两个灵感正好补上两块缺失：
> - **需求洞察**：不确定性不是抽象的信息缺口，而是**某个具体需求的阻塞**。先问「这个歧义挡住谁的需求、违反它有多贵、它属于 must-be 还是 delighter」，再问「值不值得查」。同时承认人给出的回答是**有策略偏差的测量**，不是关于需求真值的下载。
> - **技术路线图**：反复出现、当前能力永远消解不了的歧义，不是交互素材，而是**能力缺口**。它应该进入一张带依赖、成熟度、阶段门与杀死条件的路线图，用一次性能力投资去摊薄未来的复发成本。
>
> 核心命题：**把 R69 的单时间尺度「现在问谁」升级为双时间尺度「ask / build / accept」三路分流——用需求洞察决定哪些不确定性值得管，用技术路线图决定哪些不确定性不该再问、而该去建一种能力；三者都必须可证伪、有权属、可追溯、过门控，否则退回 R69 纯保守。** 命名 **NEEDLE-RAS**（Need-Evidence-gated Development & Long-horizon Escalation for Risk-adaptive Systems）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**这个不确定性到底在服务谁的需求，值不值得为它建一种能力**」——最贵的错误不是答错，而是极其严谨地回答了一个没人需要的问题。

## 0. 直觉与动机

**灵感 1（需求洞察 → 不确定性有主人，也有价签）**
直觉：R69 用熵给歧义定价，隐含假设每个模态错误一样贵。但真实需求是分层的：碰撞是 must-be，桌面摆得整齐是 delighter；同样 5cm 的位姿歧义，落在 must-be 需求上是事故，落在 delighter 需求上只是不完美。需求洞察把问题从「歧义有多大」换成「歧义挡住了谁的需求、违反它有多贵」。Kano 模型给了一个可操作的非对称损失：must-be 违反代价大、满足后收益饱和；delighter 反之。于是 U_epi 不再是标量熵，而是**需求加权遗憾**。

**灵感 2（需求洞察 → 说出来的不是真需求）**
直觉：R69 把人当 oracle——问一句，取回一个关于世界的真值。但「你想让我走哪边」往往不是事实问题，而是偏好问题；而偏好有三层：说出来的（stated）、做出来的（revealed）、还没被说出的（latent）。人会策略性回答、会迎合、会前后不一致。因此需求不是待查询的常量，而是待辨识的隐变量；交互是**带偏的测量**，不是下载。需求洞察 = 用主动查询做逆偏好/逆效用建模，同时用 revealed 行为给 stated 回答去偏。最关键的是：**冲突不要平均掉，冲突本身就是需求不确定性**。

**灵感 3（技术路线图 → 反复出现的不确定性是能力缺口，不是提问素材）**
直觉：R69 对每个 episode 的 U_epi 都问一次。如果某类歧义每个 episode 都复发，而现有传感器/技能永远消解不了，R69 就会永远问——这正是交互疲劳的根。技术路线图给出正确的会计：一次交互是 per-episode 的 O(1) 成本；建一种能力是一次性 C，但会在未来 T 个 episode 上摊薄。于是存在盈亏平衡时域 `T* = C/[f(ρ−ρ')]`：复发频率 f 越高、单次遗憾 ρ 越大、能力残余 ρ' 越小，越应该「停止问、开始建」。这把「未消解的 epistemic」从负债变成投资标的。

**灵感 4（技术路线图 → 能力获取是期权，不是承诺）**
直觉：路线图最容易退化成愿望清单。工程上真正约束它的是依赖、成熟度和证据门：TRL 1–9、概念→台架→硬件在环→闭环样机→现场，每级只回答它能回答的问题；未过门不许晋级，失败可 kill/pivot；能力上线前必须重认证。用**实时期权**而不是静态 NPV：早期投入买的是「继续或放弃」的权利，能抑制承诺升级（sunk-cost fallacy）。这样路线图是**带杀死条件的投资组合**，不是五年规划 PPT。

**灵感 5（双时间尺度 → ask / build / accept 三路分流）**
直觉：把 R69 的单时间尺度决策升级为三路：现在就问（ask）、立项去建（build）、接受残差并保守（accept）。三者价值分别是 `V_u`、`B_u`、`A_u`，选择 argmax。R69 恰好是「永不 build」的边界；「永远问」是 build 成本被当成无穷大的退化。这个三分法让系统第一次能说：「这个不确定性我不问了，因为它不是问题，是缺一个传感器/技能；我把它放进路线图，本 episode 先保守。」

**灵感 6（治理 → 需求洞察会退化为需求幻觉）**
直觉：一旦系统能自己提出需求，就有了自指风险：它可以用一个不可证伪的「潜在需求」解释任何交互，再用这个需求为任何能力项目背书。需求洞察于是变成确认偏误，路线图变成部门扩权。必须加两道硬约束：需求假设**必须可证伪**（存在可观测的决策差分），且 latent 需求**不得自行升格**为 must-be；must-be 的认定权属于外部 owner。否则 R70 不是更懂人，而是更会替人编需求。

## 1. 形式化定义（增量：定义 310–325）

**定义 310（NEEDLE-RAS 总览）** NEEDLE-RAS = (RIM, RWV, CGL, RDM, SGE, NRT, RCG, RAS-WM‡)。三不变式：
(i) **实时流零学习写操作**（继承定义 293-i）：需求后验与路线图只读，微调/能力部署均发生在低频离线侧；
(ii) **需求可证伪且有权属**：任何需求假设 n 必须附带可观测的决策差分证书 D(n) 与外部 owner(n)；latent 需求不得自行升格为 hard constraint；
(iii) **能力部署门控**：任何新能力进入运行时前，必须通过 SGE 分级证据与 C-RAS-WM‡ 重认证；未过门则路线图冻结、退回 R69。

**定义 311（三层需求模型 RIM）** 人类需求状态 `θ = (θ_hard, θ_soft, θ_latent) ∈ Θ`，行为/交互史 h。后验 `q(θ|h) ∝ p(h|θ)p(θ)`。三层证据：
- stated `S`：人显式说出的需求（含策略性偏差）；
- revealed `R`：从选择、纠正、接管、放弃中反推的偏好；
- latent `L`：由任务结果与上下文推断、尚未被说出的需求。
证据算子 `E_S, E_R, E_L`，`q(θ|h) = fuse(E_S, E_R, E_L)`。冲突时不得简单平均：定义冲突集 `K = {θ : LR(S,R;θ) > τ_k}`，冲突本身作为需求不确定性保留，而不是当作噪声。

**定义 312（Kano 类与需求显著度）** 每个需求假设 n 带 Kano 类 `κ(n) ∈ {must-be, performance, delighter, indifferent, reverse}`。损失非对称：must-be 违反代价 `L⁻_n` 大、满足收益饱和；delighter 相反。模态 m 的需求显著度
`σ(m) = Σ_n w_n · κ_n · P_q(m 违反 n)`，
其中 `w_n` 为需求后验权重。must-be 设权重下限 `w_min`，防止被「平均」掉。

**定义 313（需求加权不确定性 U_req）** 给定动作模态分布 `{m_k, ŵ_k}` 与人类效用 `U_H(a,θ)`，需求遗憾
`R_req(π,o) = E_{θ~q}[ max_a U_H(a,θ) − E_{a~π} U_H(a,θ) ]`。
`U_req = R_req(π,o)`；模态级分解 `U_req,k = ŵ_k · R_req(m_k,o) · σ(m_k)`。R69 的 `U_epi` 是 `σ≡1` 且 `U_H` 对模态均匀时的特例。

**定义 314（需求覆盖与盲区）** 需求覆盖矩阵 `C ∈ [0,1]^{N×M}`，`C_{n,j}` 为能力 j 对需求 n 的满足度；`cov_n = max_j C_{n,j}`。盲区 `B = {n : cov_n ≤ 1−ε_n}`。需求盲区不是交互问题：再问也不会提高 `cov_n`。

**定义 315（可证伪需求假设）** n 可采纳 iff 存在上下文 x 使策略差分
`D(n) = sup_{a,o} ‖π_{q∪n}(a|o) − π_q(a|o)‖ ≥ δ_d`，
且 D(n) 可在有限时域内被独立观测检验，同时 `owner(n) ≠ ⊥`。不满足者进入「未验证需求池」，不得驱动交互或路线图。这是对抗需求幻觉与自我确认的第一道门。

**定义 316（能力缺口账本 CGL）** 需求 n 为能力受限，若 `∀a ∈ A_cap(t), F(a;n) ≤ 1−ε_n`（当前可达动作/观测集无法满足）。缺口
`g = (n, c_⊥, evidence_infeasible, f_g, ρ_g)`，
其中 `c_⊥` 为缺失能力类别，`f_g` 为单位时间复发频率，`ρ_g` 为平均需求遗憾。CGL 是跨 episode 的持久账本：R69 的 U_epi 只在 episode 内存在，CGL 让「未消解的歧义」第一次有记忆。

**定义 317（能力路线图 DAG 与三时域）** 路线图 `G = (C, E, H)`，节点能力项目 c 带成熟度 `m_c ∈ [0,1]`（映射 TRL 1–9）、成本分布、时长、依赖前驱 `pre(c)`、对可达集的影响 `ΔA_cap(c)` 与对需求覆盖的增益 `Δcov_c`。三时域：H1 本 episode（交互）、H2 数周（技能/传感器/工具）、H3 数月（架构/任务级重构）。路线图是 DAG 而非列表：依赖未满足的项目不可排程。

**定义 318（阶段门与实时期权价值）** 每个 c 有门 G0–G4（概念/台架/硬件在环/闭环样机/现场），门证据谓词 `φ_i` 在启动前预注册。部署资格
`deploy(c,t) ⇔ 全部门通过 ∧ C-RAS-WM‡ 重认证 ∧ J_FLUID 回归通过`。
项目价值用实时期权：
`OV(c,t) = E[max(0, V_{t+1}(after c) − V_{t+1}(without c))] − C_c(t)`，
按阶段折现；门失败则 kill/pivot，已花费视为沉没成本，不因「已经投入」而继续。

**定义 319（双时间尺度升级规则）** 对每个歧义类 u 计算一次性交互收益 `V_u = VoI_req(g*) − c_int`；年化能力收益 `B_u = f_u·(ρ_u − ρ'_u)·T_h − C_u`；接受残差风险的价值 `A_u = −ρ_u`。三路选择
`choose(u) = argmax{ask: V_u, build: B_u, accept: A_u}`，
s.t. 安全与预算。若 build 胜出，则生成/更新路线图条目，本 episode 不再重复问；若 `V_u ≤ c_int` 且 `B_u ≤ 0`，走 R69 纯保守。阈值关于 `f_u、ρ_u` 单调。

**定义 320（路线图组合优化）** 在预算 `B_t`、依赖 E、风险约束下：
`max_{S_t ⊆ C} Σ_{c∈S_t} E[ΔR_req(c)] − λ_risk·Risk(c)`
s.t. `pre(c) ⊆ S_t`，`cost(S_t) ≤ B_t`，且未过门项目只允许「研发投入」、不允许「运行接入」。用拉格朗日/背包近似；这是低频离线优化，不进入实时环。

**定义 321（需求校准门 RCG）** 需模型必须校准且可反驳：
(a) stated-vs-revealed 一致性 `ECE_need ≤ τ_need`；
(b) 反谄媚：对问句做 leading-question 扰动，需求后验漂移 `≤ δ_syc`；
(c) 负控制：注入「无行为差异」的伪需求，模型不得将其提升为 must-be；
(d) 漂移监测：`D_KL(q_t‖q_{t−k}) > τ_drift` 触发路线图重规划，而非静默适应。
任一失败 ⇒ 冻结 latent→hard 升格与 build 决策，退化为 R69。

**定义 322（需求-证据-能力追溯矩阵 NRT）** 矩阵 `T: n → (evidence, capability, gate, certificate)`。任一已部署能力必须能反查到它服务的需求、支持该需求的证据、通过的阶段门与对应证书；任一 must-be 需求必须至少有一条已认证能力或显式「已接受风险」记录。T 随路线图版本化，可审计。

**定义 323（需求投毒与路线图俘获威胁模型）** `ℰ_NEED = ℰ_poison × ℰ_need-hallucination × ℰ_roadmap-capture × ℰ_requirement-drift`。包括：伪造需求、把 delighter 说成 must-be、用「为你好」诱导路线图投资、供应商/部门自利推动能力项目、历史数据选择偏差。并入 AIC。

**定义 324（证书 J_NEED）** `J_NEED = (J_FLUID, need_model_version, ECE_need, sycophancy_score, falsifiability_pass_rate, coverage_vector, gap_ledger_hash, roadmap_version, gate_evidence_hash, owner_signatures, needle_ver)`。Valid ⇔ `Valid(J_FLUID) ∧ ECE_need ≤ τ_need ∧ 所有 must-be 需求有覆盖或已接受风险 ∧ 路线图变更均有权属与门证据`。

**定义 325（退化与严格包含）** 当 (i) 需求先验均匀（`σ≡1`、κ 全等）、(ii) CGL 为空或所有 build 的 `B_u ≤ 0`、(iii) RCG 失败或路线图未授权时，NEEDLE-RAS 逐指令退化为 FLUID-RAS；安全侧不弱于 R69，实时路径不增加任何学习写操作。

# IP-264 RIM：三层需求模型（stated / revealed / latent，冲突保留）
class RequirementInsightModel:
    def posterior(self, h, ctx):
        s = self.stated_head(h)                 # 显式需求，含策略偏差
        r = self.revealed_head(h, ctx)          # 选择/纠正/接管/放弃
        l = self.latent_head(h, ctx)            # 结果与上下文推断
        q, conflict = self.fuse(s, r, l)        # 冲突不平均，进入 K
        return q, conflict

    def kano(self, n): ...                      # must-be / performance / delighter

    def salience(self, mode, q):                # 定义 312
        return sum(q.w[n] * q.kappa[n] * q.violate(mode, n) for n in q.needs)

# IP-265 RWV：从熵 VoI 改为需求遗憾 VoI
def requirement_voi(modes, q, o, g, budget):
    base = expected_regret(modes, q, o)         # 定义 313
    post = expected_regret_after(modes, q, o, g)
    return base - post - interaction_cost(g)    # <= 0 则不交互

# IP-266 CGL：把复发且能力受限的歧义记账，而不是反复问
def update_gap_ledger(ledger, unresolved, q, o):
    for u in cluster_ambiguities(unresolved):
        if capability_blocked(u, q, o):         # 定义 316
            ledger.upsert(u, f=decay(ledger.f(u)) + 1,
                          rho=ewma(ledger.rho(u), expected_regret(u, q, o)))
    return ledger

# IP-267/268 RDM + SGE：带阶段门与杀死条件的能力投资组合
def plan_roadmap(ledger, dag, budget, horizon):
    cand = [c for c in dag if deps_ready(c, dag)]
    for c in cand:
        c.option = option_value(c, horizon)     # 定义 318，非静态 NPV
        c.gate_ok = all(phi(c, e) for phi, e in zip(c.gates, c.evidence))
    # 未过门只能研发投入，不能运行接入
    return knapsack(cand, budget, risk=RiskGate(), deploy_only_if=c.gate_ok)

def stage_gate(c, new_evidence):
    passed = all(phi(new_evidence) for phi in c.gates)
    if not passed:
        return "kill_or_pivot"                  # 反承诺升级：沉没成本不续命
    return "deploy" if recertify(c, RAS_WM_DD) else "hold"

# IP-274 主闭环：R69 的实时路径不变，仅在不确定性处置处插入三路分流
def NEEDLE_RAS_round(M, obs):
    z, o = M.mtm.forward(obs)
    c, U_cal, thr = M.cof.step(o)               # R68 标定
    q, conflict = M.rim.posterior(M.history, o) # 低频更新，实时只读
    K = 1 if M.fmp.mode_head(z) < TAU_MODE else 4
    samples = M.fmp.sample(o, K)
    U_ale, U_epi, modes, _ = M.aud.decompose(samples, z, M.fmp.mode_head)
    # 1) 需求加权：不是所有 U_epi 都一样贵
    u_req = {m: M.rim.salience(m, q) * mode_regret(m, q, o) for m in modes}
    # 2) 三路分流：ask / build / accept
    action = M.triage.choose(modes, q, M.ledger, M.roadmap, M.budget)
    if action.kind == "ask" and not M.rcg.frozen:
        ans = M.cia.execute(action.g)           # 走 R69 的认证+证据纪律
        U_epi_after = M.cia.update_belief(modes, ans)
    elif action.kind == "build":
        M.ledger.add(action.gap)                # 本 episode 不再重复问
        M.roadmap.submit(action.program)        # 低频离线排程
        U_epi_after = U_epi                     # 未消解，先保守
    else:
        U_epi_after = U_epi                     # accept：显式接受残差
    # 3) 风险缩放与执行：与 R69 相同
    U_floor = U_ale + U_epi_after
    lam = max(M.efs.risk_scale(...), lam_floor(U_floor))
    A = M.ach.propose(x_prime, H=M.vista.H)
    k = M.c_ras_wm.certified_prefix(A, ..., wm_preds)
    mode = select_mode(modes, U_epi_after, lam)
    tau = M.pi_sigma.prefix_dispatch(mode.a[:k]) * lam
    # 4) 审计与证书：新增需求可证伪性、路线图权属、门证据
    M.vqa_n.submit_async(action, q, conflict, M.roadmap.version)
    return k, lam, mode, (U_ale, U_epi_after), action

## 3. 推导

**引理 19（需求加权优于熵加权）** 当 `U_H` 对模态非均匀（must-be 违反代价远大于 delighter）时，按熵选交互可能把预算花在「熵大但遗憾小」的歧义上；按需求遗憾选交互的期望遗憾下降 ≥ 熵准则，且当 `U_H` 对模态均匀时两者等价。要点：熵只度量「不确定」，不度量「不确定挡了谁」；需求权重把后者补上。

**引理 20（ask → build 的盈亏平衡）** 设某歧义类每 episode 复发概率 f，单次交互成本 `c_int`，单次遗憾 ρ，能力一次成本 C、残余遗憾 ρ'。持续 ask 的累计成本 `f·c_int·T`，build 的累计净收益 `f·(ρ−ρ')·T − C`。故 `T* = C/[f(ρ−ρ')]`；`T > T*` 时 build 严格优于 ask。系：复发频率越高、单次遗憾越大，越应把问题从交互账本移到路线图账本。

**引理 21（不可证伪需求不改进决策）** 若需求假设 n 对所有上下文满足 `D(n) = 0`，则 `π_{q∪n}` 与 `π_q` 在可观测量上不可区分；任何声称的收益都不可识别，而 n 只会扩大操纵与过度建设面。故 RCG 排除此类 n 不损失可达的遗憾下降。

**定理 18（三路分流的最优性与单调阈值）** 在歧义类平稳、成本可加、模型已知的假设下，逐类选择 `argmax{V_u, B_u, A_u}` 在三类工具中期望遗憾最小；ask/build 的胜出区域关于 `f_u、ρ_u` 单调扩大。R69 是「build 永不入选」的边界；「永远 ask」是 `C_u → ∞` 的退化。因 accept 始终可行，NEEDLE-RAS 的每步风险 ≤ R69 的纯保守上界。

**定理 19（严格包含与部署安全）** 在定义 325 的条件下，NEEDLE-RAS 与 FLUID-RAS 逐指令相同。任何能力部署必须通过 SGE 全门与 C-RAS-WM‡ 重认证，故运行时安全证书不变式保持；路线图更新是低频、原子、版本化且可回滚的，不会在 episode 内制造控制突变。需求后验/路线图只读，实时流仍无学习写操作。

# IP-264 RIM：三层需求后验（冲突保留）
class RequirementInsightModel:
    def posterior(self, h, ctx):
        s, r, l = self.stated(h), self.revealed(h, ctx), self.latent(h, ctx)
        q, conflict = self.fuse(s, r, l)        # 冲突进入 K，不平均
        return q, conflict
    def salience(self, mode, q):                # Kano 加权显著度
        return sum(q.w[n]*q.kappa[n]*q.violate(mode, n) for n in q.needs)

# IP-265 RWV：需求遗憾 VoI
def requirement_voi(modes, q, o, g):
    return expected_regret(modes, q, o) - expected_regret_after(modes, q, o, g) - cost(g)

# IP-266 CGL：复发且能力受限 → 记账，不反复问
def update_gap_ledger(ledger, unresolved, q, o):
    for u in cluster_ambiguities(unresolved):
        if capability_blocked(u, q, o):
            ledger.upsert(u, f=decay(ledger.f(u))+1, rho=ewma(ledger.rho(u), expected_regret(u, q, o)))

# IP-267/268 RDM + SGE：期权 + 阶段门 + 杀死条件
def plan_roadmap(ledger, dag, budget, horizon):

    for c in cand:
        c.option  = option_value(c, horizon)    # 非静态 NPV
        c.gate_ok = all(phi(c, e) for phi, e in zip(c.gates, c.evidence))
    return knapsack(cand, budget, risk=RiskGate(), deploy_only_if=lambda c: c.gate_ok)

    return "deploy" if recertify(c, RAS_WM_DD) else "hold"

## 4. 推导

**引理 19（需求加权优于熵加权）** `U_H` 对模态非均匀时，熵准则可能把预算花在「熵大但遗憾小」的歧义上；需求遗憾准则的期望遗憾下降 ≥ 熵准则；损失均匀时二者等价。要点：熵只度量「不确定」，不度量「不确定挡了谁」。

**引理 20（ask → build 盈亏平衡）** 持续 ask 成本 `f·c_int·T`；build 净收益 `f·(ρ−ρ')·T−C`；`T* = C/[f(ρ−ρ')]`。`T>T*` 时 build 严格优于 ask。系：复发频率与单次遗憾越高，越应把问题从交互账本移到路线图账本。

**引理 21（不可证伪需求不改进决策）** 若 `D(n)=0` 对所有上下文成立，则 `π_{q∪n}` 与 `π_q` 可观测行为不可区分；声称的收益不可识别，只会扩大操纵与过度建设面。故 RCG 排除此类假设不损失可达的遗憾下降。

**定理 18（三路分流最优性与单调阈值）** 在歧义类平稳、成本可加、模型已知下，逐类 `argmax{V_u,B_u,A_u}` 在三类工具中期望遗憾最小；ask/build 胜出区域关于 `f_u、ρ_u` 单调扩大。R69 = 「build 永不入选」边界；「永远 ask」= `C_u→∞` 退化。因 accept 始终可行，每步风险 ≤ R69 纯保守上界。

**定理 19（严格包含与部署安全）** 定义 325 条件下 NEEDLE-RAS 与 FLUID-RAS 逐指令相同；能力部署必须过 SGE 全门与 C-RAS-WM‡ 重认证，运行时安全证书不变式保持；路线图更新低频、原子、版本化、可回滚，不在 episode 内制造控制突变；实时流仍无学习写操作。

## 7. 本轮最大风险

**一句话**：NEEDLE-RAS 把「未消解的歧义」变成可投资的路线图，但需求是不可辨识且可自我确认的隐变量——系统可以发明一个不可证伪的「潜在需求」来解释交互，再用它为能力项目背书；需求洞察遂成确认偏误，技术路线图遂成自我授权的长期工程，系统可能用三年时间极其严谨地建造一个没人需要的功能。

**次级风险与缓解**：伪需求/需求幻觉（定义 315 决策差分 + RCG 负控制 + E308）；Kano 误分类（must-be 权重下限 + owner 签署 + NRT）；路线图俘获与承诺升级（阶段门杀死条件 + 实时期权 + VQAuditor-N + E313）；需求漂移（定义 321d 触发重规划）；能力上线破坏证书（RAS-WM‡ 重认证 + J_FLUID 回归 + 版本化回滚）。
