# 第 13 轮（新循环第 1 轮）· LEASE-VF：把远程 VLA 当成有时延的遥操作员，用示教轨迹管和租约式中间件接管最后 3 厘米

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份确认不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新灵感循环第 1 轮，研究线承接第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO。三个灵感词是「遥操作」「示教学习」「中间件」。本轮不推倒 CHUNK-SERVO 的 30 步规划 + 5 步执行，而是把它最弱的三个隐含假设拆开：**远程 VLA 是唯一权威、示教只用来取一个目标、网络时延只是工程细节。** 对应的新判断是：**远程 VLA 是一个有时延的遥操作员；33k 示教不只是成功轨迹，也是人类操作员的修正记录；中间件不是胶水，而是决定「谁在什么时候拥有控制权」的仲裁层。**

## 0. 先给结论：29.7% 之后，缺的不是更大的模型，而是「远程操作员 + 本地助手」的分工

第 12 轮把 30 步开环 chunk 改成「30 步规划 + 5 步视觉伺服」，回答的是**什么时候修正**。它默认了三件事：

1. **VLA 是唯一权威**：只要 plan 在，就按 plan 执行；伺服只是小修正。
2. **示教只用来取目标**：从 33k 成功演示里检索一个「目标-夹爪相对位姿」，然后做 IBVS/PBVS。
3. **时延只是工程问题**：RTT 高就降增益、加 chunk，实在不行回退。

这三件事在自由空间基本成立；在接触密集、人为干扰、跨城网络下会同时失效：

- **语义在远程，接触在本地。** VLA 能说出「把杯子挂到杯架上」，但它看到的世界比动作晚 100–300 ms；最后 3 厘米的接触事件发生在两次 `get_action` 之间。
- **规划在远程，控制频率在本地。** 30 步 chunk 是 1 秒；G1 的低层控制远高于此。中间这 1 秒没有任何「本地智能」。
- **信任在远程，安全和恢复在本地。** 网络抖动、GPU 排队、模型采样失败时，远程 plan 可能迟到或语义错误；本地没有一套独立的、可解释的「保底技能」。

本轮的核心判断是：

> **不要继续把远程 VLA 当成一个「无所不能的大脑」。把它当成一个有时延、会犯错、但语义很强的遥操作员；在机器人本地放一个由 33k 示教轨迹训练出来的「共享控制助手」；中间件负责在两者之间分配权限。**

三个灵感词正好对应三层：

| 灵感词 | 落到哪里 | 关键动作 |
|---|---|---|
| **遥操作** | 远程 VLA = 有时延的遥操作员；本地助手 = 共享控制/虚拟夹具 | 用遥操作理论处理时延、权限、稳定性；用示教数据挖掘操作员的修正动作 |
| **示教学习** | 33k 成功演示 → 对象坐标系下的「轨迹管」+ 修正原语库 | 不学第二个策略；把示教变成几何先验和恢复技能 |
| **中间件** | 每端口独立的实时执行层 | 租约（lease）、截止时间调度、优雅降级、端口隔离 |

所以本轮的押注是 **LEASE-VF**：

> **L**ease-based **E**xecution **A**rbitration with **S**hared **E**xpertise and **V**irtual **F**ixtures——用「租约」表示远程 VLA 的一次 plan 在多长时间内有效；用对象坐标系下的示教轨迹管（D-VF）和示教修正原语（D-RP）作为本地助手；中间件按 plan 年龄、网络时延、轨迹管不确定性和接触状态，平滑地把控制权从 VLA 移交给本地助手，再移回来。

一句话：**VLA 负责「做什么」，本地示教助手负责「最后 3 厘米怎么稳」，中间件负责「VLA 迟到时谁来接管」。**

### 1.3 接口：最新 README 的 metadata 是 `obs_delta_indices` + `image_resize` + `action_chunk_size` + `token`（A）

2026-10-31 复核 `unibot_submission` 最新 README：

```python
{
    "control_space":     "joint" | "ee",
    "obs_delta_indices": {key: [offset, ...]},  # 选哪些观测 + 堆叠几帧
    "image_resize":      {key: [H, W]},          # 每路图像的目标分辨率
    "action_chunk_size": int >= 1,               # 每次 get_action 返回的时间轴长度
    "token":             str
}
```

关键点：

- `obs_delta_indices` 的 key 决定**哪些观测会被发送**；value 是相对当前帧的偏移列表，必须 ≤0 且严格递增；`observation.language` 的偏移必须是 `[0]`。
- `image_resize` 可以降低传输/推理开销；key 必须已经在 `obs_delta_indices` 里。
- `action_chunk_size` 是固定值；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action`。**chunk 内没有新观测，也没有打断机制。**
- 评测端逐调用记录延迟、波动和动作统计规律，作为结果可信度的一部分。
- 观测仍是四路 RGB 480×640；没有 depth、camera_info、force/torque、tactile。动作仍是 `joint` 或 `ee` 互斥；`ee` 是 base 系绝对位姿 xyz+rpy。

**关键推论**：如果 `action_chunk_size=30`、控制频率 30Hz，一次调用后有 **1 秒开环执行**；如果 RTT=100ms，实际「看到的世界」比动作晚 100ms 以上。LEASE-VF 不改变这个接口事实，而是用本地助手填满 chunk 内的空窗，并把 `action_chunk_size` 固定为 5（或实测后的 3–8）。

| **π0.5** | Physical Intelligence 的开放世界泛化 VLA | 语义/新场景泛化 | 接触密集任务的精度；远程部署延迟 |
| **GigaBrain-0** | 世界模型生成数据 + VLA；用世界模型降真机数据依赖 | 数据效率/泛化 | 生成数据的物理保真度；最后 3 厘米 |
| **GR00T N1.5** | NVIDIA 通用人形 VLA | 生态/embodiment | 任务特定精度；数据覆盖 |

共同点：

- 都是 action chunk 开环执行；chunk 内不看新图。
- 模型越大，chunk 越长，越不反应；长 chunk 与接触精度直接冲突。
- 世界模型解决「想象未来」，不解决「现在偏了 2mm」。
- 单模型规则让「再加一个学习残差」危险；但「确定性共享控制器」不是模型。

### 1.7 相关前沿：虚拟夹具、共享控制、恢复数据、实时服务都已经成熟到可以组合（A）

- **虚拟夹具/共享控制**：从示教轨迹分布生成 tube-shaped virtual fixture，用协方差调刚度，用 energy tank 保证被动性；2025–2026 年有多篇工作把它做到自适应、几何感知、稀疏示教。([Adaptive VF](https://doi.org/10.1109/thms.2025.3540123), [Unified probabilistic VF](https://arxiv.org/abs/2506.10239), [Geometry-aware VF](https://arxiv.org/abs/2609.32958))
- **遥操作时延**：wave variables、time-domain passivity、energy tank 是成熟工具；可以把远程策略的命令流当成有时延的遥操作信号。([Passive MPC teleoperation](https://doi.org/10.1109/tro.2025.3554447), [Wave variable compensators](https://www.mdpi.com/2079-9292/14/13/2595))
- **示教中的修正/恢复**：RaC、Genie Centurion、RoboCopilot、PGDG、RESample、Rewind-IL 都证明「恢复/修正数据」比纯成功 BC 更能提升长程鲁棒性；我们可以从成功示教里挖修正段，而不需要新采失败数据。([RaC](https://arxiv.org/abs/2509.07953), [PGDG](https://arxiv.org/abs/2605.21710), [RESample](https://arxiv.org/abs/2510.17640), [Rewind-IL](https://arxiv.org/abs/2604.16683))
- **实时 VLA 服务**：Armory 把多机器人 action chunk 调度形式化为闭环 MDP；RTC 用 freezing + inpainting 做异步 chunk 执行；ActECC/FlashVLA 把时延和 chunk 可用范围做成系统级问题。([Armory](https://arxiv.org/abs/2608.00337), [RTC](https://arxiv.org/abs/2506.07339), [FlashVLA](https://arxiv.org/abs/2608.27384))

这些工作说明：**「VLA 规划 + 本地快速反馈」是 2026 年的前沿，但还没有人把它做成「单模型合规 + 示教轨迹管 + 租约式权限仲裁 + 每端口中间件」的组合。**

## 2. 诊断：三个「远程/本地」错位

把一次失败拆开看：

```text
t0: 观测 → 远程 VLA 推理 (100-300ms) → 返回 30 步 chunk
t0+0.1s: evaluator 开始执行 chunk
t0+0.1s … t0+1.1s: 机器人开环执行 30 步
        ↑ 接触/滑移/人移动物体都发生在这一段
t0+1.1s: 才看到下一帧 → 已经晚了
```

三个错位：

1. **语义/接触错位**：VLA 的强项是「看懂场景、决定做什么」；它的弱项是「在接触瞬间做毫米级闭环」。把两者都压在同一个远程模型上，是用错工具。
2. **规划/控制错位**：远程 plan 是 1 Hz 级的；本地控制是 30 Hz 级甚至更高。中间缺一个「本地技能层」，能在 plan 之间维持稳定、执行修正、处理接触。
3. **信任/安全错位**：远程 plan 可能迟到、抖动、语义错误；本地没有独立的「保底技能」。一旦网络或 GPU 出问题，机器人只能停在原地或继续执行过期 plan。

LEASE-VF 的答案不是「更大的 VLA」，而是**分工**：

```text
远程 VLA：语义意图 + 30 步粗规划（低频、强语义）
本地助手：示教轨迹管 + 修正原语 + 接触监控（高频、弱语义、确定性）
中间件：租约/权限/截止时间/端口隔离（实时、可观测）
```

## 3. 方法：LEASE-VF

### 3.1 总架构

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐

                    │  ├─ plan lease + authority α(t)     │

                    │  ├─ contact/stall/edit monitor      │
                    │  └─ action adapter (WLA 54D → API)  │
                    └──────────────┬──────────────────────┘
                                   │ async, batched, EDF
                                   ▼
                    ┌─────────────────────────────────────┐

```

- **唯一学习模型**：VLA（官方 WLA 微调 action head）。
- **本地助手**：D-VF + D-RP；确定性控制器/几何先验，无在线学习权重。
- **数据资产**：33k 成功演示 → 轨迹管索引 + 修正原语库；不是第二个策略。
- **中间件**：每端口独立会话、共享 GPU 后端、EDF 调度、租约仲裁、优雅降级。

### 3.2 D-VF：对象坐标系下的示教轨迹管

不要把示教只压缩成一个「目标位姿」。把每个任务/阶段的对齐轨迹变成一个**分布**：

```text
离线：
  对每个任务 t、每个阶段 p：
    用 DTW 对齐该阶段的 N 条示教 EE 轨迹（位置 + 姿态）
    重采样到统一相位 s ∈ [0,1]
    在对象坐标系 O 下表示：X_i(s) = T_O^{-1} · T_ee_i(s)
    对每个 s 拟合均值 μ(s)、协方差 Σ(s)（位置 3D + 旋转切空间 3D）
    可选：用 GMM 保留多模态（不同抓取/接近策略）
    存：μ(s), Σ(s), 阶段边界, 对象锚点, 示教 ID

在线：
  估计当前对象位姿 T_O(t)（头双目 + 局部 ICP / 第 11 轮几何）
  估计当前相位 s（VLA plan index + 视觉进度）
  取当前阶段的 μ(s), Σ(s)，变换到 base 系：
    μ_B(s) = T_O(t) · μ(s)
  把 VLA 的绝对 EE 命令 x_vla 投影到管中心：
    e = μ_B(s) - x_vla
    w_i = (1 - α) · exp(-σ_i² / (2σ_0²)) · 1[||e|| ≤ R]
    x_cmd = x_vla + diag(w) · clip(e, ±r_max)
```

性质：

- **位置泛化**：对象移动 → `T_O(t)` 变 → 管跟着移动。
- **人为干扰**：人移动目标 → 重新估计 `T_O(t)` → 管跟着移动；如果目标被拿走，管失效 → 触发恢复。
- **未见物品**：管的几何由受器/任务决定；外观变化由 VLA 处理。
- **背景/干扰物**：D-VF 只用对象坐标系和局部几何，不依赖全局背景。
- **多模态**：GMM/检索保留多条接近策略；当前状态选最近的一条；不确定时降低刚度。
- **各向异性**：插入任务中，横向方差小 → 横向刚度高；轴向方差大 → 轴向柔顺。这正是「插入漏斗」。

与 DG-KEYFRAME 的区别：DG-KEYFRAME 检索一个「目标-夹爪相对位姿」；D-VF 检索/拟合**整段未来轨迹的分布**，提供连续引导、相位进度和不确定性，而不是一个终点。

### 3.3 D-RP：从成功示教里挖「遥操作修正原语」

33k 示教不只是成功轨迹；它们记录了人类操作员的停顿、回退、重抓。我们可以把这些段挖出来，变成确定性的恢复原语：

```text
离线：
  对每条示教：
    检测修正事件：
      - 夹爪闭合且 EE 速度 < v_stall 持续 > 0.2s（停顿）
      - 相邻速度方向反转，且随后位移 > d_rev（回退）
      - 夹爪开/合变化 > g_thr 且随后重新接近（重抓）
      - 在接触阶段出现上述模式（用相位/距离过滤）
    截取 [事件起点, 重新接近结束] 的段
    在对象坐标系下归一化，聚成 K 类原语：
      retreat(d), lateral_shift(d), rotate(θ), re_grasp(open/close), re_approach(v)
    存：原语参数、适用任务/阶段、触发条件、持续时间

在线：
  monitor 检测：
    - stall: 相位 s 连续 N 步不前进
    - contact: 跟踪误差大且不下降
    - slip: 物体相对夹爪位姿变化 > 阈值
    - edit: 场景变化无法用机器人动作解释（第 11 轮 GEO-RESIDUAL）
  触发最近邻原语：
    a_recover = primitive.execute(obs, T_O(t))
  原语执行期间 α=0（本地全权）；结束后重新请求 VLA plan，α 平滑恢复
```

关键点：

- **不需要失败数据**：修正段来自成功示教；这是「从遥操作数据中学习恢复」。
- **不是第二个策略**：原语是参数化轨迹/动作序列，由确定性 monitor 触发；没有学习到的观测→动作映射。
- **与 D-VF 共用对象坐标系**：恢复后能无缝回到轨迹管。
- **人为干扰轴**：这是性价比最高的单项；检测到场景被编辑后，先退、再重定位、再恢复，而不是继续追旧目标。

### 3.4 LEASE-MW：租约式权限仲裁 + 截止时间调度

「租约」是中间件的核心抽象：远程 VLA 的一次 plan 不是永久有效，而是有一段时间窗；在窗内 VLA 有高权限，窗外本地助手接管。

```text
每个 plan 带：
  t_plan: 生成时刻
  H: 30 步
  T_lease = H_c / f_c + τ_max   # 当前 chunk 的执行时间 + 最大可接受 RTT
  c: 置信度（可选：采样一致性/plan 与 D-VF 的一致性）

权限：
  age = t - t_plan
  α = clip((T_lease - age) / T_lease, 0, 1) · c
  VLA 权重 α；D-VF/D-RP 权重 1-α
  age ≥ T_lease → α=0，本地助手全权；同时异步请求新 plan

调度：
  每个端口的 get_action 不阻塞 GPU；只读最新 plan + 本地助手
  共享后端用 EDF（earliest deadline first）批处理 N 个端口
  deadline_i = t_plan_i + T_lease_i - τ_est_i - ε
  如果某端口迟到：
    - 本地助手延长租约（继续当前阶段）
    - 降低该端口请求的分辨率/帧率（优雅降级）
    - 不阻塞其他端口
```

为什么是「租约」而不是「固定 chunk」：

- chunk 长度是接口固定的，但**信任长度**可以是动态的；租约把「plan 新鲜度」显式化。
- 网络抖动时，租约自然缩短 VLA 权限，避免执行过期 plan；网络好时，租约让 VLA 主导，本地助手只做轻量投影。
- 每个端口独立租约；共享后端只负责推理，不共享会话状态。
- 评测端记录延迟/波动；租约+EDF+优雅降级直接优化 p99 和 starvation。

可选的**被动性/能量槽 governor**（备份，不进核心）：

- 把远程命令流看成有时延的遥操作信号；用 `E_inj ≈ Σ F_cmd · v_meas Δt` 估计注入能量；
- 当 `E_inj > 0` 且租约将过期时，增加阻尼/降低 D-VF 刚度，避免 chunk 边界振荡；
- 这是 teleoperation 的 energy tank 思想，但 API 没有力传感器，只能用 PD 控制力代理；只在高 RTT 抖动时启用，作为 G5 的兜底。

### 3.5 与 CHUNK-SERVO 的关系

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定为第二个模型 | D-VF/D-RP 是确定性控制器/轨迹先验；默认用非参数检索，不加载第二个网络；提交材料写清 C1/C2/C3 |

| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |

**合规主线**：VLA 是唯一的学习策略；D-VF 是「几何轨迹先验 + 投影控制器」；D-RP 是「参数化轨迹原语 + 确定性触发器」；LEASE-MW 是「调度/仲裁」。如果官方要求更严格的单模型解释，提交 VLA-only 基线 + 中间件，D-VF/D-RP 只作为离线分析。

### 1.2 提交接口（A）

最新 README（2026-10-31 复核）给出的 metadata：

```python
{
    "control_space":     "joint" or "ee",       # 互斥
    "obs_delta_indices": {key: [offset, ...]},  # 选观测 + 时间堆叠
    "image_resize":      {key: [H, W]},          # 图像目标分辨率
    "action_chunk_size": int >= 1,               # 固定
    "token":             str
}
```

关键事实：

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640** |
| 本体 | 双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str` |
| 动作空间 | `joint` 或 `ee`，二者互斥 |
| 共享动作 | `action.left_gripper [1]`、`action.right_gripper [1]`、`action.pivot [7]` |
| EE 动作 | `action.left_ee_pose_gripper_base [6]`、`action.right_ee_pose_gripper_base [6]`（绝对目标位姿，xyz+rpy，base 系） |
| chunk | `action_chunk_size` ≥1，固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action` |
| token | `metadata.token` 握手校验一次；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile** |
| 监控 | 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分 |
| 观测选择 | `obs_delta_indices` 的 key 决定哪些观测被发送；value 是 ≤0 且严格递增的帧偏移 |
| 图像缩放 | `image_resize` 可降低传输/推理开销；key 必须已在 `obs_delta_indices` 中 |

**关键推论**：`action_chunk_size=30`、控制频率 30Hz 时，一次 `get_action` 之后有 **1 秒开环执行**；chunk 内没有新观测，也没有打断机制。租约/本地助手必须在这个空窗内工作。控制频率未在 README 中写死；本报告默认 30Hz，必须在单任务通道实测。

## 2. 问题形式化

### 2.1 评分与不确定性

总分：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

320 trials 下，若 `p≈0.25`，单次标准误：

```math
\mathrm{SE}(S)\approx \sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

配对 A/B 的方差取决于任务内相关；若同一初始条件的 A/B 成功高度相关，配对差值方差可显著降低。报告必须给配对差值的 bootstrap 置信区间，而不是只报两个平均值。

人为干扰轴：

```math
\Delta S_{\mathrm{human}} = \frac{2}{10}\,\Delta p_h = 0.2\,\Delta p_h.
```

即 human 轴成功率 +10pp → 全局 +2pp。

### 2.2 远程执行时间模型

设：

- `f_c`：evaluator 控制频率（假设 30Hz，需实测）；
- `H_c`：提交的 `action_chunk_size`；
- `τ`：网络 RTT + 推理 + 图像传输的等效延迟；
- `T_fb`：从「世界变化」到「策略看到变化」的反馈周期。

则：

```math
T_{\mathrm{fb}} \approx \frac{H_c}{f_c} + \tau,
\qquad
T_{\mathrm{lease}} = \frac{H_c}{f_c} + \tau_{\max}.
```

| 场景 | `H_c` | `f_c` | `τ` | `T_fb` | 评价 |
|---|---:|---:|---:|---:|---|
| 官方 WLA 默认 | 30 | 30 | 50ms | **1050ms** | 接触段基本开环 |
| 本方案保守 | 5 | 30 | 50ms | **217ms** | 可做 1–2 次接触修正 |
| 本方案乐观 | 5 | 30 | 20ms | **187ms** | 需低 RTT |
| 本方案高延迟 | 5 | 30 | 150ms | **317ms** | 租约缩短 VLA 权限 |
| 低控制频率 | 5 | 10 | 50ms | **550ms** | 改 `H_c=3` 或只做 D-VF |
| 极低延迟 | 3 | 30 | 20ms | **120ms** | 动态任务可用 |

**结论**：`H_c` 必须按实测 `f_c` 和 `τ` 选；不能把 30 步默认值直接搬到远程 API。租约 `T_lease` 是「VLA 权限」的时间窗，不是 chunk 长度。

### 2.3 共享控制形式化

设 `x_vla` 为 VLA 的绝对 EE 命令，`μ(s), Σ(s)` 为当前相位 `s` 的示教轨迹管，`α ∈ [0,1]` 为 VLA 权限。定义误差和投影：

```math
e = \mu(s) - x_{vla},
\qquad
w_i = (1-\alpha)\,\kappa\,\exp\!\left(-\frac{\sigma_i^2}{2\sigma_0^2}\right)\mathbf{1}[\|e\|\le R],
```

```math
x_{cmd} = x_{vla} + \mathrm{diag}(w)\,\mathrm{clip}(e,\,\pm r_{\max}).
```

- `α=1`：完全信 VLA；`α=0`：完全信 D-VF。
- `σ_i` 小（示教一致）→ 刚度高；`σ_i` 大（多模态/不确定）→ 刚度低。
- `R` 是有效性半径；`||e||>R` 时夹具失效，允许 VLA 离开管（避障、换策略）。
- `r_max` 限幅，避免夹具压过 VLA 的语义意图。

### 2.4 可辨识性条件

D-VF 只在以下条件同时满足时启用：

1. 当前任务/阶段有足够的示教（≥30 条）；
2. 对象/受器位姿可估计（头双目 ROI 有效 ≥70%，或已知静态受器）；
3. 轨迹管的中位半径 ≤ 阈值（例如 1.5cm / 5°）；
4. 当前状态在管的有效性半径 `R` 内；
5. 任务属于刚体/准刚体接触（A 档）。

任一条不满足 → 回退 VLA 或 D-RP；不硬做 D-VF。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port LEASE endpoint (CPU)      │
                    │  ├─ session/state isolation         │
                    │  ├─ plan lease + authority α(t)     │
                    │  ├─ D-VF: demo trajectory tube      │
                    │  ├─ D-RP: recovery primitives       │
                    │  ├─ contact/stall/edit monitor      │
                    │  └─ action adapter (WLA 54D → API)  │
                    └──────────────┬──────────────────────┘
                                   │ async, batched, EDF
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared VLA server (GPU)            │
                    │  UnifoLM-WLA-1.0 / VLA-0, 30-step   │
                    └─────────────────────────────────────┘
```

- 每个端口一个 `Session`：独立 `reset()`、plan、租约、相位、D-VF/D-RP 状态、历史。
- 共享 VLA server 用 session ID 区分端口；模型权重只有一份，不违反单模型。
- 本地助手是 CPU 线程，不阻塞 websocket；VLA 请求异步、可批处理。
- GPU 6B bf16 约 12GB；一张 24GB/40GB GPU 可服务多个端口，具体并发取决于 batch 和序列长度。

### 3.2 接口契约

提交 metadata 示例：

```python
{

        "observation.language":                         [0],
        "observation.images.cam_left_high":             [0],
        "observation.images.cam_right_high":            [0],
        "observation.images.cam_left_wrist":            [0],
        "observation.images.cam_right_wrist":           [0],
        "observation.state.left_ee_pose_gripper_base":  [-2, 0],

        "observation.state.left_gripper":               [0],

    "image_resize": {
        "observation.images.cam_left_high":  [240, 320],
        "observation.images.cam_right_high": [240, 320],
        "observation.images.cam_left_wrist": [128, 128],
        "observation.images.cam_right_wrist":[128, 128],
    },
    "action_chunk_size": 5,
    "token": os.environ["UNIBOT_SUBMISSION_TOKEN"],

```

注意：

- `observation.language` 的 offset 必须是 `[0]`（标量字符串，无时间轴）；其余键先用 `[0]` 取当前帧；EE 位姿用 `[-2,0]` 估计速度。
- 若 WLA 训练配置要求多帧堆叠，按配置改成 `[-4,-2,0]` 等，并保持 offset ≤0、严格递增。
- `image_resize` 只对已在 `obs_delta_indices` 中的 key 生效。

**观测/语言适配**：挑战赛 `*_ee_pose_gripper_base` 是 xyz+rpy；WLA server 的 `*_ee_6d` 实际是 **xyz+rot6d（9 维）**，obs adapter 必须做 rpy→rot6d。图像映射为 `cam_left_high` + 左右腕部三路；`cam_right_high` 只用于双目深度/对象定位。语言方面，WLA server 用 `unnorm_key`/固定 prompt，不直接吃挑战赛的 `observation.language`；需要把 32 任务语言映射到 WLA 的任务 key（或空 prompt），并在单任务通道验证。

动作返回（`ee` 模式）：

```python
{
    "meta.token": token,
    "action.left_gripper":  np.float32 (5,1),
    "action.right_gripper": np.float32 (5,1),
    "action.pivot":         np.float32 (5,7),
    "action.left_ee_pose_gripper_base":  np.float32 (5,6),  # absolute xyz+rpy
    "action.right_ee_pose_gripper_base": np.float32 (5,6),  # absolute xyz+rpy
}
```

注意：挑战赛 API 的 EE 动作是**绝对目标位姿**；WLA 输出的是**相对当前 EE** 的 xyz+rotvec。adapter 必须先 compose 到当前 EE 绝对位姿，再叠加 D-VF 投影。

### 3.3 D-VF 管线

#### 3.3.1 离线

```text
for each task t:
    for each episode e:
        phases = segment(e)                    # 夹爪开合 + 速度 + 接触距离
        for each phase p:
            X_e,p = align_dtw(e, p)           # 位置 + 姿态
            X_e,p = resample(X_e,p, s ∈ [0,1])
            X_obj = inv(T_O(e)) @ X_e,p        # 对象坐标系
            store(task=t, phase=p, demo=e, X_obj, descriptor, T_O(e))
    for each (t,p):
        fit μ(s), Σ(s) on X_obj             # 或保留非参数检索
        store(μ, Σ, phase boundaries, anchor, quality)
```

#### 3.3.2 在线

```text
estimate T_O(t) from head stereo + classical geometry
estimate phase s from VLA plan index + visual progress
retrieve/fit μ_B(s), Σ_B(s) = T_O(t) @ (μ(s), Σ(s))
compute e = μ_B(s) - x_vla
compute w_i = (1-α) * κ * exp(-σ_i²/(2σ_0²)) * 1[||e|| <= R]
x_cmd = x_vla + diag(w) * clip(e, ±r_max)
```

#### 3.3.3 对象坐标系

- **静态受器**（杯架、网口、试管架、锁）：用头双目 + 平面/圆/线拟合；对象位姿在 episode 内可视为常量，位置泛化时重新估计。
- **可移动物体**（杯子、水果、工具）：用头双目 + 局部 ICP/颜色分割；人为干扰后重新估计。
- **透明/反光/变形**：置信度低 → 降低 D-VF 刚度或关闭；退回 VLA。
- **不用第二个学习检测器**：只用经典几何/颜色/深度；避免单模型合规风险。

#### 3.3.4 多模态

- 先用非参数检索：对每个 `(task, phase)` 建 kd-tree，查询 `x_obj, gripper, descriptor` 的 k 近邻；用近邻的未来轨迹算均值/协方差。
- 若轨迹模式明显（不同抓取/接近），用 GMM/DTW k-means 分 K 类；在线选后验最高的分量。
- 置信度低时用混合分布的协方差（更宽）→ 刚度更低；不要硬选一个模式。

### 3.4 D-RP 管线

#### 3.4.1 修正事件检测

```text
v_t = (p_{t+1} - p_t) * fps
stall_t   = ||v_t|| < v_stall for n_stall frames and gripper closed
reverse_t = v_t · v_{t+1} < -eps and ||p_{t+Δ} - p_t|| > d_rev
regrasp_t = |g_{t+1} - g_t| > g_thr and re-approach follows
contact_t = phase in {insert, hang, zip, lock, stack} or d_t < d_c
event_t   = contact_t and (stall_t or reverse_t or regrasp_t)
```

#### 3.4.2 原语库

```text
for each event:
    seg = [event_start, re_approach_end]
    seg_obj = inv(T_O(t)) @ seg
    primitive = fit_parametric(seg_obj)   # retreat(d), lateral(d), rotate(θ), regrasp, re_approach(v)
    store(task, phase, primitive, trigger_stats)
cluster primitives by DTW/geometry; keep K prototypes per (task, phase)
```

#### 3.4.3 在线触发

```text
monitor:
  stall_score   = frames since progress
  contact_resid = tracking error / visual residual
  slip_score    = change in object pose relative to gripper
  edit_score    = scene change unexplained by robot action (GEO-RESIDUAL)

if max score > threshold:
    primitive = nearest(task, phase, current geometry)
    execute primitive with α=0
    after primitive: request VLA re-plan; ramp α back
```

#### 3.4.4 与 D-VF 的关系

- D-VF 是「沿着示教管走」；D-RP 是「走偏/卡住时退回管里」。
- 两者共用对象坐标系和相位；恢复后可以直接回到 D-VF。
- D-RP 不替代 VLA 的语义重规划；它只处理「局部退让/重抓/重接近」这类确定性动作。

### 3.5 LEASE-MW 调度

#### 3.5.1 租约

```text
Plan:
  actions[30]
  t_plan
  H = 30
  T_lease = H_c / f_c + τ_max
  c = confidence (optional)

Authority:
  age = now - t_plan
  α = clip((T_lease - age) / T_lease, 0, 1) * c
  if α < α_min: local assistant full authority
  if α > α_max: VLA full authority (D-VF still lightly projects)
```

#### 3.5.2 EDF 调度

```text
requests: (port_id, obs, deadline, priority)
deadline = t_plan + T_lease - τ_est - ε
sort by deadline (EDF)
batch up to B_max; if batch would miss deadline, reduce batch or resolution
return plans asynchronously; endpoint never blocks
```

#### 3.5.3 优雅降级

- 端口 A 的 plan 迟到 → A 的 D-VF/D-RP 延长租约；不阻塞端口 B/C。
- GPU 过载 → 对低优先级端口降低 `image_resize` 或跳过本次 plan；高优先级端口保持。
- 网络抖动 → `τ_est` 更新，`T_lease` 缩短；α 更快衰减。
- 记录每个端口的 plan age、α、p50/p99、starvation；用于离线调参和提交材料。

#### 3.5.4 状态隔离

- 每个端口独立 `Session`：`plan`、`lease`、`phase`、`tube_state`、`recovery_state`、`history`。
- 共享后端只保存模型权重和 batch 队列；不保存任何端口状态。
- `reset()` 清空该端口的 session；不影响其他端口。

### 3.6 动作适配（WLA 54D → 挑战赛 21D）

```text
WLA 54D:
  left_ee_rel[6], left_gripper[1], left_hand[6],
  right_ee_rel[6], right_gripper[1], right_hand[6],
  waist[3], torso[3], base_vxvy[2], base_wz[1],
  base_pose_rel[6], height[1], left_leg[6], right_leg[6]

挑战赛 ee 21D:
  left_ee_abs[6], right_ee_abs[6],
  left_gripper[1], right_gripper[1], pivot[7]
```

映射：

1. `left_ee_abs = compose(T_base_ee_left_current, exp(left_ee_rel))`；转 xyz+rpy。
2. `right_ee_abs` 同理。
3. gripper 直通（按挑战赛的 0–1 方向校验）。
4. `pivot = [vx, vy, wz, yaw, pitch, roll, height]`，从 WLA base/waist 组合；具体符号/顺序必须用 `example_env.py` 和单任务通道验证。
5. 腿部/灵巧手在挑战赛 `ee` 模式下不直接下发；若 `pivot` 需要下身体，按官方 WLA server 的 `action.pivot` 语义映射。

**关键细节**：WLA 的每个未来动作是「相对 plan-time 当前 EE」的位姿（compose 后才是 base 系绝对目标），不是累积增量；adapter 必须先把整个 30 步 compose 成 base 系绝对目标，再按 5 步切片。否则切片后的第 6–30 步会以错误的锚点解释，产生系统性偏移。

**帧/TCP 风险**：WLA 的 EE 帧与挑战赛的 `*_ee_pose_gripper_base` 帧可能差一个 TCP/夹爪长度偏移；必须用 `example_env.py` 的观测和真实数据做一次手眼/工具坐标校准（平移 ≤1cm、旋转 ≤2°）。这是 G6 的第一验证项。

**风险**：`pivot` 的 7 维语义在挑战赛 README 中只写「Lower-body / pivot target」，没有逐维定义；这是 adapter 的第一验证项（G6）。若 `pivot` 语义不匹配，先返回全零 pivot（保持下身体不动），只验证双臂；不要猜符号。

class LeaseVFPolicy:
    def __init__(self, task, token):
        self.task = task
        self.token = token
        self.session = Session(task)
        self.vla = AsyncVLAClient()
        self.dvf = DemoTubeIndex(task)
        self.drp = RecoveryPrimitiveLibrary(task)
        self.mw = LeaseMiddleware(self.session)
        self.H_c = 5

    def get_action(self, obs):
        now = time.monotonic()
        self.session.observe(obs, now)
        plan = self.mw.latest_plan()
        phase, s = self.mw.estimate_phase(obs, plan)

        # D-VF: retrieve/fit the local tube
        tube_mu, tube_sigma = self.dvf.query(
            task=self.task, phase=phase, s=s, obs=obs
        )

        # authority: VLA vs local assistant
        alpha = self.mw.authority(plan, now, tube_sigma)

        # nominal VLA chunk (or local continuation if plan is stale)
        if plan is not None:
            a_vla = plan.actions[self.mw.plan_index : self.mw.plan_index + self.H_c]
        else:
            a_vla = self.dvf.continue_current_phase(obs, phase, self.H_c)

        # project VLA command into the demo tube
        a_cmd = self.dvf.project(
            a_vla, tube_mu, tube_sigma, alpha,
            r_max=0.01, R=0.03, sigma0=0.02,
        )

        # recovery overrides
        if self.mw.detect_failure(obs):
            a_cmd = self.drp.execute(obs, phase, self.H_c)
            self.mw.set_authority(0.0)

        # request next plan if lease is about to expire
        self.mw.maybe_request_plan(obs, now, self.vla)

        self.mw.advance(self.H_c)
        return self.adapter.to_api(a_cmd, obs, self.token)

`LeaseMiddleware`：

```python
class LeaseMiddleware:
    def __init__(self, session):
        self.session = session
        self.plan = None
        self.plan_ts = None
        self.plan_index = 0

    def latest_plan(self):
        return self.plan

    def authority(self, plan, now, tube_sigma):
        if plan is None:
            return 0.0
        age = now - self.plan_ts
        alpha = max(0.0, min(1.0, (self.T_lease - age) / self.T_lease))
        return alpha * self.confidence(plan, tube_sigma)

    def maybe_request_plan(self, obs, now, vla):
        if self.plan is None or (now - self.plan_ts) > self.T_lease - self.tau_est - self.eps:
            if not self.inflight:
                self.inflight = True
                vla.request(obs, callback=self._on_plan)

    def _on_plan(self, plan):
        self.plan = plan
        self.plan_ts = time.monotonic()
        self.plan_index = 0
        self.inflight = False
```

## 4. 推导

### 4.1 轨迹管/协方差

位置：

```math
\mu_p(s)=\frac{1}{N}\sum_{i=1}^N x_i(s),
\qquad
\Sigma_p(s)=\frac{1}{N-1}\sum_{i=1}^N (x_i-\mu_p)(x_i-\mu_p)^\top+\Sigma_0.
```

姿态：把每个旋转 `R_i(s)` 投影到均值旋转 `\bar R(s)` 的切空间：

```math
\xi_i(s)=\mathrm{Log}\left(\bar R(s)^\top R_i(s)\right),
\qquad
\Sigma_R(s)=\frac{1}{N-1}\sum_i \xi_i\xi_i^\top+\Sigma_{R,0}.
```

管半径：对每个特征方向 `j`，`r_j(s)=\sqrt{\chi^2_{6}(\beta)\,\lambda_j(s)}`，其中 `\lambda_j` 是协方差特征值。工程上用 `r_j = k_\sigma \sigma_j`，`k_\sigma=2` 或 3。

### 4.2 投影/刚度

```math
w_i=(1-\alpha)\,\kappa\,\exp\left(-\frac{\sigma_i^2}{2\sigma_0^2}\right)\mathbf{1}[\|e\|\le R],
\qquad
x_{cmd}=x_{vla}+\mathrm{diag}(w)\,\mathrm{clip}(e,\pm r_{\max}).
```

- 如果 `σ_i` 很大（多模态/示教不一致），`w_i→0`，不强行把 VLA 拉到一个不确定的均值。
- 如果 `σ_i` 很小（示教一致），`w_i→(1-α)κ`，强引导。
- `R` 允许 VLA 在管外自由运动；`r_max` 防止夹具压过语义意图。
- 姿态用同样的公式，在切空间做；可按局部轴各向异性（插入轴强、接近轴弱）。

### 4.3 租约/权限

```math
\alpha(t)=\mathrm{clip}\left(\frac{T_{lease}-(t-t_{plan})}{T_{lease}},0,1\right)c.
```

- `α` 随时间线性衰减；`c` 是可选置信度（plan 采样一致性、与 D-VF 的一致性、动作平滑度）。
- `α < α_min` → 本地助手全权；`α > α_max` → VLA 主导。
- 租约不是「plan 有效期」的物理保证，而是「权限分配」的工程抽象；即使 plan 过期，D-VF 仍可继续当前阶段。

### 4.4 时延稳定性/能量槽

简化离散积分器：

```math
e_{k+1}=e_k-K H_c\,e_{k-d},
```

其中 `d=τ/(H_c/f_c)` 是延迟块数。特征方程：

```math
z^{d+1}-z^{d}+K H_c=0.
```

- `d=0`：`|1-KH_c|<1` → `0<KH_c<2`。
- `d=1`：`z^2-z+KH_c=0`；稳定域 `0<KH_c<1`；增益裕度约减半。
- `d=2`：稳定域进一步缩小；必须降增益或加预测。

可选能量槽：

```math
E_{t+1}=E_t-\Delta t\,(F_{cmd}\cdot v_{meas}),
\qquad
F_{cmd}\approx K_p(x_{cmd}-x)+K_d(v_{cmd}-v).
```

- `E_{t+1}<0` → 按比例缩小 D-VF 修正/加阻尼，直到 `F_cmd·v_meas≤0`。
- 这是「passivity-inspired」代理，不是严格保证；只在 G5 显示高 RTT 振荡时启用。

### 4.5 恢复原语触发

```math
s_{stall}=\max(0,\,n_{no-progress}-n_0),
\qquad
s_{contact}=\max(0,\,\|e_{track}\|-\epsilon_0),
```

```math
s_{slip}=\max(0,\,\|\Delta T_{obj,gripper}\|-\delta_0),
\qquad
s_{edit}=\max(0,\,edit\_score-\theta_e).
```

`trigger = max(s_stall, s_contact, s_slip, s_edit) > 1`。触发后执行最近邻原语；原语结束后重新请求 VLA plan，`α` 从 0 平滑恢复。

## 8. 风险与合规

### 8.1 单模型合规的三种模式

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | D-VF/D-RP 只离线生成相位/管/原语；线上只有 VLA | 最低 | 保守首选 |
| C2 确定性控制器 | D-VF 是几何投影控制器；D-RP 是参数化轨迹原语 + 确定性触发器；无在线学习权重 | 低；需向官方说明 | 主推 |
| C3 同 checkpoint 特征 | 检索描述子用 VLA 同一 checkpoint 的 encoder，不加载第二个模型 | 低–中；需说明 | 需要强描述子时用 |

禁止：加载第二个学习策略/残差网络/独立视觉编码器做在线任务决策。

### 8.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定为第二个模型 | C1/C2/C3；默认非参数检索；提交材料写清 |
| 对象位姿估计 | 透明/反光/遮挡失败 | 头双目 + 经典几何；置信度门控；退回躯干系/VLA |
| 示教分布窄 | 位置/未见物品泛化不足 | 对象坐标系重锚定；多模态；有效性半径；降低刚度 |
| 修正原语不匹配 | 恢复动作错误 | 任务/阶段/几何过滤；top-k 重打分；回退 VLA |
| 远程 RTT 高 | 租约频繁过期 | EDF + 优雅降级 + 本地助手延长；clamp α；p99 监控 |
| 租约抖动 | chunk 边界不平滑 | α 平滑；动作插值/低通；可选能量槽 |
| `pivot` 语义不一致 | 动作被拒/机器人不动 | 先用 `example_env.py`/单任务通道验证；零 pivot 回退 |
| 标定漂移/换机器人 | 对象锚定/手眼误差 | 每机器人一次重投影校准；夹爪 PnP 自标定；误差大关 D-VF |
| 人为干扰不在视野 | 漏检 | 本体/夹爪/任务状态兜底；不声称 100% |
| 安全 | 回撤/重抓碰撞 | 限速/限幅/最大重试；恢复前先退；D-VF 有效性半径 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |
| 提交次数限制 | 无法多次 A/B | 邮件确认；单任务通道先验证；一次提交则保守 |
