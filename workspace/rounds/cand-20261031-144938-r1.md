# 第 1 轮 · AXIS-GRAPH：把五类泛化轴与官方评分步骤编译成数据与监督

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。
>
> 编号说明：本轮是新循环第 1 轮，三个灵感词是「**数据增强**」「**通用机器人平台**」「**常识推理**」。状态文件上一版是上一循环第 12 轮 **CHUNK-SERVO**（30 步 VLA 规划 + 5 步视觉伺服 + 演示检索 + 数字孪生标定）。按“每轮深化与修剪、不推倒重来”的规则，本轮把 CHUNK-SERVO 保留为执行层，在其上补**数据层**和**监督层**。

## 0. 一句话结论

**榜首只有 29.7%，而 10 次评测里有 6 次是背景/干扰物/未见物品、2 次是位置、2 次是人为干扰；训练数据每任务约 1000 条、初始位姿标准差仅约 5cm。最值得押注的不是再训一个更大的 VLA，而是把官方 5 类泛化轴和 32 个任务的评分步骤编译成“轴对齐、动作保持、多视角一致”的反事实数据与辅助监督，让同一个 WLA 在数据层吸收泛化、在监督层学会步骤进度、在执行层保留 CHUNK-SERVO 的闭环。**

本轮主押注：**AXIS-GRAPH = AXIS-AUG（五轴反事实数据编译器）+ STEP-GRAPH（评分步骤弱监督/进度头）+ CHUNK-SERVO（执行层闭环）**。

## 1. 本轮核实的事实（只列会改变方案的）

### 1.1 赛事、榜单与提交

- **规则不变**：32 任务；每任务 10 次；5 类泛化各 2 次（位置、干扰物、桌面背景、未见物品、人为干扰）；单次上限 180s；排名先看 32 任务总平均成功率，再看总平均步骤分，最后看更早提交；仅通才模型赛道，必须同一模型跑完 32 任务，禁止混合多个模型；模型类型不限（World Model / VLA 均可）。
- **提交方式**：选手自部署，官方远程调用；N 台机器人对应 N 个连续端口，从 **8765** 起；每端口独立交互，`reset()` 状态隔离；另有不计分的单任务测试通道。
- **榜单（2026-10-31 抓取）**：MolmoAct2/DexHacker **29.7%**/39.0；WALL-OSS-0.5/Generalist Robotics 28.5%/38.9；DreamZero/World Model Lab 27.9%/37.9；Spirit-v1.5/VLAGO 25.9%/34.4；DM0/Embodied AI Institute 23.5%/31.7；π0.5/RoboReasoner 22.8%/30.6；GigaBrain-0/xembody 22.6%/29.5；GR00T N1.5/Humanoid Dynamics 20.5%/28.1。头尾差 9.2pp，说明不是单一架构领先，而是共享瓶颈。
- **榜单可信度**：`leaderboard_data.json` 的 `generated_from` 为 `gen_leaderboard.py`，发布时间 **2026-10-08**；页面仍标注「即将发布/Coming Soon」。上一轮回归发现 `step ≈ k_model × success` 的 R² > 0.999999、10 次 trial 出现 27.29%/27.85% 等非 10% 整数倍、详情页视频为占位。结论：**把榜单当预览/上限信号，不当 SOTA，也不当任务难度表**。
- **提交 API（README/example 复核）**：`metadata` 含 `control_space`（`"joint"` / `"ee"` 互斥）、`obs_delta_indices`、`image_resize`、`action_chunk_size`、`token`；`get_action(obs)` 返回固定长度 action chunk；`reset()` 每 episode 调用；`observation.language` 为标量字符串且 offset 必须 `[0]`；图像原生 **480×640**；offset ≤0 且严格递增。示例 `ACTION_CHUNK_SIZE = 8`，图像堆叠示例 `[-10,-5,-2,0]`。
- **上一轮已核对、本轮未逐条重验的约束**：API 无 depth、camera_info、force/torque、tactile；chunk 内无新观测、无打断机制。若最新 README 有变化，以 README 为准。

### 1.2 数据：量大但“窄”

- 官方 HF collection `unitreerobotics/unibot-v1-challenge-dataset` 共 32 个数据集，collection 更新于 **2026-09-11**；官方挑战页写 **32,000 episodes / 169 h**。
- 2026-10-31 逐数据集读取 `meta/info.json`，合计 **33,276 episodes / 18,282,246 frames / 169.28 h**，全部 30 fps，机器人主体为 `unitree_g1`（FoldTowel 为 `unitree_g1_8520`）。
- HangCup 示例：**1,043 episodes / 194,564 frames**，LeRobot v3.0，4 路 AV1 480×640 视频（head_stereo_left/right、wrist_left/right）；状态含双臂 7 维、EE pose base/torso 6 维、lower_body 15 维、`state_d435` 6 维等；动作含 `pivot[7]`、`gripper_controls[4]`、`base_command[4]` 等。
- HangCup 第一个 parquet chunk：**719 episodes / 130,565 rows**；初始 EE pose 标准差约 **5cm**（左 xyz std ≈ [0.052, 0.0578, 0.026]，右 ≈ [0.0531, 0.0433, 0.0248]）；episode 长度均值 **181.6 帧**（std 37.1，min 94，max 411）；episode 元数据含 **5 条英文指令改写**。
- 这说明：数据足以训一个强基线，但**初始状态、背景、物体实例、失败恢复的多样性不足**；而评测的 10 次全部是泛化设置，没有“干净同分布”送分题。

### 1.3 官方任务信息：本轮最重要的新发现

`challenges.html` 内嵌 JS 指向 `tasks_v2/<slug>/info.json`。32 个 JSON 已抓取到 `/tmp/unibot_tasks/`，每个含：

- `task_id`（T01–T32）、`slug`、中英文名/描述；
- `difficulty_zh/en`（容易/中等/困难）；
- `scoring_points`；
- `score_steps`（2–5 步，合计 100 分）；
- `generalization`：`unseen_object_3`、`human_1_note`、`human_4_note`（部分任务为空）；
- 5 条演示视频引用。

关键例子：

- **T01 HangCup（容易）**：抓住杯把(50)；挂到杯架标记位置上(50)。未见物品提示“缺少红色杯子和塑料架子”；人为干扰“杯子向后”“杯子向右”。
- **T05 DisconnectEthernet（困难）**：夹住网口再夹住网线(50)；拔出网线(50)。干扰“把网线另一头也插上”“移动道具手握网口”。
- **T16 FoldTowel（困难）**：挥正毛巾(20)；上下对折(20)；抓住左边对折(20)；抓住右边对折(20)；对折后放到旁边(20)。干扰“将叠完的毛巾翻开”。
- **T09 ToolboxStorage（困难）**：完成 2 个工具收纳(25)；完成所有工具收纳(25)；盖上箱子盖(25)；锁上箱子(25)。
- **T21 clear_plates = ArrangePlates**，**T25 stack_cups = StoreCups**，**T27 stack_bowls_three = StackBowls**；任务 ID 与榜单顺序一致，但 slug 名称不同，做映射时不要混。
- **T31 pencil_case、T32 syring_water 的 generalization note 为空**；需要通用增强兜底，不能假装有官方提示。

这套 `score_steps + human notes` 是**免费、任务对齐、评测对齐**的弱监督：既能做步骤进度头，也能直接指导反事实数据生成。

### 1.4 WLA 与“通用机器人平台”

- `unitreerobotics/unifolm-wla`：创建 **2026-09-11**、推送 **2026-09-29**、256 stars；**UnifoLM-WLA-1.0 为 6B**，约 **2,500 h** 真机数据、**64** 任务（桌面 + 全身），支持二指夹爪和多种五指灵巧手；HF collection 更新于 **2026-09-28**，含 `UnifoLM-WLA-1.0-Base`（414 downloads）、`UnifoLM-ER-Flow`、`UnifoLM-ER-1` 等。
- `train_action_expert_en.md`：VLM backbone 冻结（`trainer.freeze_modules: qwen_vl_interface`），只训 DiT action head + robot-state projector；默认单张 **24GB GPU**；支持 `trainer.lora` LoRA；模型服务器为 websocket/msgpack。
- `unifolm_wla_action_adapter.py` 只覆盖 Dex1 二指夹爪，不含 fullbody WBT；挑战赛用 Dex1 正好匹配。
- Unitree 开源页/公开报道称 Dex1 数据集已从 32 项扩展到 **43 项**，WLA 训练用到 64 任务、2,500h。**同 embodiment 的额外数据**是“通用机器人平台”最现实的落点：不换机器人、不换动作空间，只扩物体/背景/语言多样性。

### 1.5 文献信号：数据增强与常识监督都已被验证，但没人按“评测轴”编译

- **RoboAug**（arXiv 2602.14032）：区域对比式生成数据增强，只需单图 bbox；在背景/干扰物/光照未见场景把成功率从 **0.09→0.47**（UR-5e）、**0.16→0.60**（AgileX）、**0.19→0.67**（Tien Kung 2.0）。这是“视觉泛化轴”最直接的证据。
- **Pose6DAug**（arXiv 2606.20118）：用 3D 物体替换做姿态/新物体增强，在新物体上相对提升 **16.5%**；说明“未见物品”轴可以靠 3D 资产替换显著改善。
- **CRAFT**（arXiv 2604.03552）：视频扩散生成双臂数据，canny-guided，用仿真轨迹给动作标签，支持物体位姿、颜色、背景、光照、相机、跨 embodiment、多视角增强。
- **RoboVIP**（arXiv 2601.05241）：多视角视频生成做机器人数据增强；**Grounded-Dreamer / RoboDream / SimFoundry / Splat2Act** 都在做 real-to-sim / 数字表亲 / 高斯泼溅增强。
- **Act2Answer**（arXiv 2606.19297）：用动作回答常识/世界知识题，评测 7 个 VLA + 9 个 VLM，发现 VLA 保留简单感知，但在更丰富的语义类别上相对源 VLM 明显退化。
- **ERVLA**（arXiv 2606.03784）：把 embodied CoT 当**训练期表示塑形**，而不是测试期推理，说明“常识监督进训练、推理保持单模型”是可行路线。
- **CometVLA**（arXiv 2608.30289）、**PhysBrain 1.0**（arXiv 2605.15298）、**ADAPT**（arXiv 2604.14902）分别从物理 VQA、物理常识、affordance 推理补常识。
- **CGVD**（arXiv 2603.10340）、**TAG**（arXiv 2603.24584）、**StageCraft**（arXiv 2603.20659）做训练-free 的杂乱场景引导/环境重排；说明“干扰物轴”可以用推理时手段补，但会引入延迟和额外模型风险。

**共同缺口**：这些工作大多按“通用泛化”做增强，没有把**赛题官方的 5 类轴、32 个任务的评分步骤、human_1/human_4 的具体扰动**当作 schema 来编译数据。挑战赛恰好提供了这个 schema，这是本轮创新的立足点。

## 2. 赛题再判断：分数到底丢在哪

### 2.1 60% 的分数在视觉泛化轴

10 次评测 = 5 类 × 2 次。背景、干扰物、未见物品合计 **60%**；位置 **20%**；人为干扰 **20%**。如果模型过拟合训练背景/物体，最多只能拿到 40% 的分。RoboAug/Pose6DAug 的增益说明这条轴不是“模型容量问题”，而是“数据覆盖问题”。

### 2.2 训练数据的“窄”是结构性的

每任务约 1,000 条演示、初始 EE 位姿 std 约 5cm、每任务 5 条指令改写；这能覆盖“同一场景的重复”，但覆盖不了“换背景/换物体/换位置/人把物体挪走”。官方 `unseen_object_3` 和 `human_1/4_note` 其实已经告诉我们测试会怎么变，只是没有给对应数据。

### 2.3 多步任务是第二层瓶颈

32 个任务里 2–5 步；FoldTowel 5 步、OrganizeStationery 5 步、ToolboxStorage 4 步、PackBag 4 步。失败往往不是“抓不到”，而是“做到一半忘了下一步/被干扰后不恢复”。官方评分步骤是免费监督，且步骤分是并列时的第二排序键。

### 2.4 执行层仍然需要，但不是本轮的新杠杆

CHUNK-SERVO 解决的是最后 3 厘米、1 秒开环、RTT 抖动；它仍然是对的方向。但如果没有泛化数据和步骤监督，执行层只能在“见过的场景”里把最后 3 厘米做好。本轮把 CHUNK-SERVO 保留为第三层，不重复造轮子。

### 2.5 榜单是预览，不是难度表

榜单的合成迹象意味着：不要按榜单任务成功率分配工程；用官方 `difficulty` + 单任务通道 + 自己的离线/仿真代理来选任务。把 320 trials 当投资组合，而不是把榜单当 ground truth。

### A1 · AXIS-AUG：五轴反事实数据编译器（主押注）

**动机**：评测的 60% 是背景/干扰物/未见物品，20% 是位置，20% 是人为干扰；训练数据初始位姿 std 仅约 5cm，视觉多样性不足。RoboAug 在未见背景/干扰物/光照下 +38pp（UR-5e），Pose6DAug 在新物体上 +16.5% 相对提升，证明这条轴的数据覆盖是最高 ROI。

**与现有差异**：

1. **轴对齐**：不是“随机增强”，而是把 5 类评测轴逐条映射成生成算子；每条算子有对应的验收门。
2. **动作保持/等变**：位置轴用“物体相对 EE 位姿保持”重定向动作；未见物品轴用“功能 affordance 保持”重定向抓取；不是只改图不改动作。
3. **多视角一致**：HangCup 有 4 路相机（头双 stereo + 双腕），生成后用重投影误差/遮挡一致性筛掉坏样本；这比单图 2D 粘贴更接近真机。
4. **官方 note 驱动**：`unseen_object_3` 直接告诉我们要换什么（红杯/塑料架、不同果篮、不同试管），`human_1/4_note` 直接告诉我们在哪一步、往哪个方向扰动（杯子向后/向右、拧开后再拧回、拉上后再拉开）。这比通用 human perturbation 更精准。
5. **与执行层衔接**：增强后的目标图/相对位姿进入 DG-KEYFRAME 检索库；人扰轴训练 GEO-RESIDUAL 的检测；步骤轴给 CHUNK-SERVO 提供重规划触发。

**可行性**：

- **高**：背景替换、干扰物插入、外观/颜色替换（2D 分割 + 修复/重渲染）。
- **中**：位置重定向、未见物品 3D 替换（需要深度/网格/资产 + 动作重定向 + 仿真质检）。
- **中低**：人为干扰的“动作级恢复”（需要状态匹配/仿真；先做观测级 + 测试时重规划）。
- **不建议**：对透明/反光/可变形/线缆/液体任务强行 3D 替换；这些走 2D 轴或测试时恢复。

**资源**：官方 33k 演示；SAM2/DepthAnything/GroundingDINO；3D 资产库（Objaverse/HF，需核许可）；Blender/高斯泼溅；MuJoCo/IsaacLab；1–2 张 24–80GB GPU；2–5TB 存储；2–3 人 6–8 周。

**步骤**：

1. **P0 schema**：从 32 个 `info.json` 生成 `task_schema.json`，含步骤、轴、note、难度、可 3D 化标记。
2. **P1 试点**：选 3 个刚性任务（T01 HangCup、T21 ArrangePlates、T25 StoreCups）+ 2 个困难任务（T09 ToolboxStorage、T16 FoldTowel，仅 2D）。
3. **P2 2D 轴**：背景/干扰物/外观替换；SAM2 分割 + 深度放置 + 修复/渲染；先出 1:1 增强集。
4. **P3 一致性训练**：原图与增强图动作一致性正则；轴平衡采样；WLA action head 微调。
5. **P4 3D 轴**：位置平移/未见物品替换；相对位姿重定向 + 仿真可行性检查；只对刚性任务。
6. **P5 人扰轴**：按 note 在指定阶段做观测级扰动；能拼恢复段就拼，不能就交给 CHUNK-SERVO/GEO-RESIDUAL。
7. **P6 A/B**：单任务通道 3 任务 × 10 次；过门再扩 32 任务。

**风险**：合成伪影/域 gap；动作标签错误；物理不可行；透明/反光/可变形失败；评测过拟合；数据许可。对应缓解：原图:合成 ≥1:1；多视角重投影 + 仿真可行性 + 人工抽检；3D 只做刚性任务；所有增强离线完成，推理仍单模型。

### A2 · STEP-GRAPH：把评分步骤变成弱监督（主押注第二腿）

**动机**：官方每任务 2–5 步、合计 100 分；多步任务容易中途失败；步骤分是并列时的第二排序键。Act2Answer 说明 VLA 的丰富语义会退化；ERVLA 说明“常识进训练”比“测试时 CoT”更稳；官方 `score_steps` 是免费、任务对齐的步骤标签。

**与现有差异**：

1. 不做自由形式 CoT，不在测试时调用第二个 LLM/VLM；所有辅助头都是**同一个模型**的一部分。
2. 用评分步骤做**进度头 + 下一步子目标头 + 目标 grounding 头**，而不是只做语言条件。
3. 进度信号直接接 CHUNK-SERVO：进度停滞 → 触发伺服/重规划；接近接触 → 缩短执行块。
4. 与 FACT-VLA 的相位分段对齐：FACT-VLA 是视觉相位，STEP-GRAPH 是评分步骤，二者可互相校验。

**可行性**：中。弱标签可用离线 VLM 打标 + 轨迹分段 + DTW + 人工抽检；进度头轻量；推理开销小。难点是步骤边界模糊（例如“抓住杯把”与“挂到杯架”之间的过渡）和标签噪声。

**资源**：WLA 微调；离线标注 1–2 周；单卡 24GB；不需要额外在线模型。

**步骤**：

1. 对每个任务定义步骤序列（来自 `score_steps`）。
2. 用离线 VLM 对关键帧分类当前步骤；用 EE/物体状态检测子目标完成；用 DTW 对齐到规范进度曲线。
3. 训练 `progress_head`（步骤分类/序数回归）、`next_subgoal_head`（下一步骤文本/物体热图）、`grounding_head`（目标物体/受器）。
4. 推理时用进度头触发 CHUNK-SERVO 重规划；不改变 API，不增加输入。
5. A/B：多步任务（T21/T09/T16）看成功率与步骤分。

**风险**：步骤标签噪声；进度头校准；早期失败时无增益；过拟合步骤措辞。缓解：置信度过滤 + 人工抽检；只在进度置信度高时触发；保留原始 action loss 为主。

### B1 · PLATFORM-MIX：用“通用机器人平台”扩数据，而不是换机器人

**动机**：挑战数据 169h/32 任务；Unitree Dex1 线已扩到 43 项，WLA 用 2,500h/64 任务训练。同 embodiment、同动作空间的额外数据可以扩物体/背景/语言多样性，缓解过拟合。

**与现有差异**：不是换机器人、不是跨 embodiment 大改；把 Unitree G1/Dex1 数据统一到挑战 schema，按任务/轴平衡采样，做辅助共训；推理仍是同一个 WLA。与 A1 的区别：A1 是“生成新数据”，B1 是“复用已有真实数据”。

**可行性**：高（同机器人/动作空间），但需确认数据许可、相机/动作键一致性、夹爪型号；WBT 数据与桌面任务差异大，先不用。资源：1–5TB、1–2 卡、3–4 周。

**风险**：分布不匹配、灾难性遗忘、存储、许可。缓解：挑战数据占比 ≥70%；先小规模消融；只选 Dex1 二指夹爪任务；用 held-out 挑战任务评估遗忘。

### B2 · PERTURB-RESUME：把官方 human note 变成恢复数据

**动机**：20% 评测是人为干扰；官方 note 精确到“哪个阶段、往哪个方向、拿走什么”；演示数据只有成功轨迹，没有失败-恢复对。

**与现有差异**：不是通用随机扰动；用 note 指定阶段和方向；观测级扰动 + 能拼则拼的恢复段 + 仿真恢复；与 GEO-RESIDUAL 的测试时检测结合。可行性中低，先做观测级和刚性任务。风险：状态不匹配、恢复不真实、物理不可行。判决：作为 A1 的人扰轴，不单独作为主押注。

### C1 · AUG-CONSENSUS：测试时增强共识（快速实验/兜底）

**动机**：对 K 个增强视图做前向，动作一致性高则执行，低则触发 CHUNK-SERVO；无需训练，单模型合规。可行性高，但 6B 模型 K 倍延迟，180s 预算需实测。风险：延迟、共识选错、增益不确定。判决：1 周快速实验，作为兜底，不占主工程。

### C2 · TASKGRAPH-LLM：离线任务图/增强脚本生成（工具）

**动机**：用离线 LLM/VLM 从任务描述/评分步骤生成场景图、物体清单、扰动脚本、成功检查器；不进在线策略。可行性高，但需人工审核。风险：幻觉、脚本错误。判决：工具，不计主创新。

## 4. 主押注：AXIS-GRAPH 三层栈

```text
第 3 层 执行：CHUNK-SERVO（30 步规划 + 5 步伺服 + DG-KEYFRAME + GEO-RESIDUAL）
                     ↑ 进度触发 / 目标图 / 扰动检测
第 2 层 监督：STEP-GRAPH（progress head + next-subgoal head + grounding head）
                     ↑ 步骤弱标签
第 1 层 数据：AXIS-AUG（背景 / 干扰物 / 未见物品 / 位置 / 人扰）
                     ↑ 官方 5 轴 + 32 任务 score_steps + human notes
```

- **数据层**解决“没见过”：60% 视觉轴 + 20% 位置轴。
- **监督层**解决“做到一半忘了/被干扰”：多步进度 + 恢复触发。
- **执行层**解决“最后 3 厘米”：保留上一轮 CHUNK-SERVO。
- 三层都在离线/单模型内完成，不违反单模型规则；推理时只增加轻量头，不增加第二个大模型。

**为什么不是“再训一个更大的 VLA”**：榜单头尾只差 9.2pp，说明共享瓶颈不是容量；WLA 已经 6B/2,500h；再训更大模型的时间/算力/合规成本高，且不直接覆盖 5 类轴。**为什么不是“纯世界模型”**：世界模型生成数据有前途，但训一个高质量视频扩散模型成本高、周期长；本轮先用几何/2D 编辑 + 现有 WLA，世界模型只作为后续可选项。

## 5. 本轮剪枝（明确不做）

1. **不从零训视频扩散/世界模型**：用 2D/3D 编辑 + 现有 WLA；CRAFT/RoboDream 作为后续，不进本轮关键路径。
2. **不在线加第二个模型/LLM**：所有常识/进度头都是同一模型的一部分；避免单模型合规风险和延迟。
3. **不做 full sim-to-real RL**：仿真只做增强数据质检和数字孪生标定，不训 6B 策略。
4. **不按预览榜单任务排名分配工程**：用官方 difficulty、单任务通道、离线/仿真代理。
5. **不把 WBT/全身数据硬塞进桌面任务**：先只用 Dex1 二指夹爪同构数据。
6. **不对透明/反光/可变形/线缆/液体强行 3D 替换**：这些走 2D 轴或测试时恢复。
7. **不追求“32 任务各训一个策略”**：单模型规则不允许，也不符合通才赛道。
8. **不把 `unseen_object_3` 当精确测试集**：它是提示/代理，真实测试可能更宽；增强要覆盖同类别多实例，而不是只换一个颜色。

## 6. 预期收益与 kill criteria

| 项 | 乐观预期 | 保守预期 | Kill / 继续条件 |
|---|---|---|---|
| AXIS-AUG（2D 轴） | 视觉轴 +5–10pp | +2–5pp | 3 任务单任务通道 10 次，至少 2 任务 +2 次成功；否则缩回 2D |

## 7. 一句话押注

**把官方 5 类泛化轴和 32 个任务的评分步骤编译成“轴对齐、动作保持、多视角一致”的反事实数据与进度监督，用同一个 WLA 吸收；CHUNK-SERVO 只负责最后 3 厘米的闭环——这是在不违反单模型规则、不重训大模型的前提下，最可能把 30% 推到 35%+ 的路线。**

# 第 1 轮产物 · AXIS-GRAPH 技术报告

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。
>
> 本报告是想法区「AXIS-GRAPH」的工程化产物：**AXIS-AUG（五轴反事实数据编译器）+ STEP-GRAPH（评分步骤弱监督）+ CHUNK-SERVO（执行层）**。不替换上一循环第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO；本轮把它们接到数据层和监督层。

## 0. 结论与边界

### 0.1 一句话结论

评测的 10 次全部是泛化设置（背景/干扰物/未见物品 60%、位置 20%、人为干扰 20%），而训练数据每任务约 1,000 条、初始 EE 位姿标准差约 5cm。**最高 ROI 不是再训更大的 VLA，而是把官方 5 类泛化轴和 32 个任务的评分步骤编译成反事实数据与辅助监督，让同一个 WLA 在数据层吸收泛化、在监督层学会步骤进度；CHUNK-SERVO 只负责最后 3 厘米的闭环。**

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方页面/API/数据直接核实 | 32 个 `tasks_v2/<slug>/info.json`；HF `meta/info.json` 合计 33,276 episodes / 169.28h；榜单 29.7% |
| B | 官方仓库/文档核实 | 提交 API 字段；WLA 6B/2,500h/64 任务；VLM 冻结/24GB/LoRA |
| C | 上一轮核实、本轮未逐条重验 | 无 depth/force/tactile；chunk 内无新观测；榜单合成迹象 |
| D | 文献/推断/假设 | RoboAug/Pose6DAug 增益；预期 +5–10pp；增强数据可迁移到挑战赛 |

### 0.3 边界

- 不假设能提前拿到官方真机；所有 A/B 先走单任务通道/离线/仿真代理。
- 不假设外部数据一定允许；`PLATFORM-MIX` 以“许可确认”为前置门。
- 不承诺合成数据一定涨点；每条轴都有 kill gate，过不了就缩回 2D 或 CHUNK-SERVO 单栈。
- 不把预览榜单当 SOTA 或任务难度表。

### 4.2 五轴算子

| 轴 | 输入 | 生成算子 | 动作标签 | 质检 | 适用 |
|---|---|---|---|---|---|
| **位置** | 原演示、物体/受器位姿 | 对目标物体（或受器）采样刚体变换 `D`；重渲染 4 视角 | 物体相对 EE 位姿保持，重定向 | 可达/无碰/多视角重投影 | 刚性任务 |
| **干扰物** | 原演示、桌面自由空间 | 插入 2–4 个同类别/不同类别 3D 资产；避开关键帧遮挡 | 不变（模型需忽略） | 遮挡率/物理放置/多视角 | 全部 |
| **背景** | 原演示、桌面/背景分割 | 替换桌布/背景纹理、光照色温/强度；保留阴影 | 不变 | 分割边界/光照一致/多视角 | 全部 |
| **未见物品** | 原演示、目标物体掩码 | 替换同类别不同实例（颜色/材质/形状/尺寸）；保持功能 affordance | 抓取点/相对位姿重定向 | 抓取宽度/可达/多视角 | 刚性任务 |
| **人为干扰** | 原演示、note 指定阶段 | 在指定帧对物体做平移/旋转/移除；能拼恢复段则拼 | 观测级不变；恢复段用检索/仿真 | 状态匹配/恢复可行 | 刚性优先；可变形只做观测级 |

#### 位置轴：动作重定向公式

设 `T_w_o(t)` 为物体在世界系的位姿，`T_w_e(t)` 为 EE 位姿。抓取后物体刚性附着，定义物体相对 EE：

```text
T_e_o = T_w_e(t) * inverse(T_w_o(t))
```

对物体施加世界系刚体变换 `D`（左乘），新物体位姿 `T_w_o'(t) = D * T_w_o(t)`，则新 EE 位姿：

```text
T_w_e'(t) = T_e_o * T_w_o'(t)
          = T_w_e(t) * inverse(T_w_o(t)) * D * T_w_o(t)
```

- **抓取前**：不要直接用该公式；用原演示的接近方向 + IK 检查，或对抓取点做 `D` 变换后重新规划接近段。
- **放置段**：若受器也移动 `D_r`，则放置段用 `T_w_e'(t) = D_r * T_w_e(t)`；或保持 `T_e_r`（EE 相对受器）不变。
- **夹爪开合**：保持不变；若新物体尺寸变化，按宽度比例缩放夹爪目标，并检查最大开口。
- **失败拒绝**：IK 不可达、关节限位、碰撞、物体/受器出视野 → 丢弃该变体。

#### 未见物品轴：affordance 保持

- 资产检索键：类别 + 功能部位（handle/cap/slot/rim）+ 尺寸范围 + 抓取宽度。
- 抓取点重定向：在原物体上标注功能部位（如杯把），在新物体上找对应部位；用相对部位坐标系 `T_e_part` 保持。
- 放置关系保持：如“挂”需要杯把与架子横杆的相对关系；如“拧”需要瓶盖轴线对齐；如“插”需要插头/网口轴线对齐。
- 不满足 affordance 的资产直接拒绝；不要用“看起来像”但功能部位不同的资产。

#### 干扰物轴：硬负样本

- 优先插入与目标同类别/同颜色的干扰物（例如目标红杯，插入蓝杯/红碗），逼模型用语言+功能部位区分。
- 干扰物放在桌面自由空间，避开抓取/放置关键帧的目标-夹爪连线；用深度/仿真检查不悬空、不穿插。
- 少量“部分遮挡”变体可以作为困难样本，但比例 ≤20%，避免把任务变成不可能。

#### 背景轴：不要只换颜色

- 桌布纹理、背景墙、桌面反光、光照方向/色温都变；保留目标物体的阴影和接触暗部，避免“贴图感”。
- 可以用 2D 分割 + 修复 + 重打光；也可以用 3D 场景重渲染。2D 更快，3D 更一致。
- 与 RoboAug 的区域对比损失兼容：增强时保留目标区域，背景区域做对比约束。

#### 人扰轴：按 note 指定阶段

- **观测级**：在指定帧对物体做平移/旋转/移除；训练模型检测“场景变了”，但不给恢复动作标签。适合所有任务。
- **动作级**：从其他演示中检索与扰动后状态最近的片段，拼接；或在 MuJoCo/IsaacLab 中从扰动状态规划到目标，生成恢复动作。只对刚性、状态可估计的任务。
- **分工**：AXIS-AUG 负责人扰数据；GEO-RESIDUAL 负责测试时检测；CHUNK-SERVO 负责恢复执行。三者不要把同一个问题重复实现。

### 4.3 多视角一致性

HangCup 有 4 路相机，天然适合做质检：

1. 用 SAM2 + DepthAnything 得到目标/受器掩码与深度。
2. 在 3D 中应用编辑（物体变换/替换/插入），用标定外参重投影到 4 路。
3. 检查：
   - 重投影误差：目标关键点/轮廓 < **3px**；
   - 深度一致性：编辑区域深度差 < **5mm**；
   - 遮挡一致性：4 路中的可见性变化符合几何；
   - 光度一致性：阴影方向/色温与背景一致（人工抽检）。
4. 不满足 → 丢弃，不用“后期补掩码”硬救。

> 若某任务只有单路/双路可用，降低到 2D 轴，不做 3D 替换。

### 4.4 质量门（G1–G3）

| 门 | 指标 | 通过线 | 不过怎么办 |
|---|---|---|---|
| G1 分割/深度 | IoU / depth error | IoU > 0.90；深度 < 5mm | 换 SAM2 提示/补深度；仍不行则只用 2D 背景 |
| G1 多视角 | 重投影误差 | < 3px | 丢弃该变体；检查标定 |
| G1 仿真 | 可行性 | 无碰/可达/限位通过 > 90% | 缩小 `D` 范围；换资产 |
| G1 人工 | 抽检 | 每轴/任务 20 条，通过 > 80% | 调整算子/提示 |
| G2 动作保真 | held-out 原演示 action error | 退化 < 5% | 降合成比例；加 consistency loss |
| G2 轴增益 | 增强轴 action error | 相对降 > 10% | 检查标签/增强质量 |
| G3 域 gap | real vs synthetic 判别器 AUC | 越接近 0.5 越好（参考） | 加原图、降合成比例、改渲染 |

## 5. STEP-GRAPH：评分步骤弱监督

### 5.1 步骤对齐

对每个任务，`score_steps` 给出 K 个步骤（K=2–5）。对每条演示：

1. **关键帧采样**：每秒 2–4 帧，或按 action 变化采样。
2. **离线 VLM 打标**：用 Qwen2.5-VL/InternVL，prompt 给任务描述 + 步骤列表，输出当前步骤索引 + 置信度；不参与在线推理。
3. **轨迹/物体状态分段**：检测夹爪闭合、物体抬起、物体进入受器、盖子合上等事件；用 DTW 对齐到规范进度曲线。
4. **融合**：VLM 标签 + 事件 + DTW；置信度低/冲突的帧标 `ignore`；人工抽检 5%。
5. **输出**：每帧 `step_index`、`step_progress`（0–1）、`next_step`、`target_object/receptacle` 伪标签。

> 步骤边界模糊是常态；不要追求逐帧完美，训练时用软标签/ignore 区间，推理时只用高置信度进度。

### 5.2 辅助头与损失

在 WLA 的 VLM 特征上接轻量头（不改变 VLM）：

```text
progress_head:     VLM feature -> K-way step logits + step progress
next_subgoal_head: VLM feature -> next-step text embedding (contrastive)
grounding_head:    VLM feature -> target/receptacle box or mask
remaining_head:    VLM feature -> remaining steps (ordinal)
```

损失：

```text
L = L_action
  + λ_prog * L_progress        # CE / ordinal (CORAL), ignore low-confidence
  + λ_sub  * L_subgoal         # InfoNCE with step text embeddings
  + λ_grnd * L_grounding       # BCE/DICE on SAM2/GroundingDINO pseudo-labels
  + λ_rem  * L_remaining       # ordinal regression
  + λ_cons * L_consistency     # original vs observation-only augmented action
```

建议初始权重：`λ_prog=0.1`、`λ_sub=0.05`、`λ_grnd=0.05`、`λ_rem=0.02`、`λ_cons=0.05`；用验证集调，不要压过 action loss。

### 5.3 推理时怎么用

- **不改变 API**：`action_chunk_size` 仍是固定值；进度头在每个 chunk 推理时计算。
- **进度停滞**：若同一 `step_index` 连续 N 个 chunk 无进展（N=2–3），或进度置信度骤降 → 触发 CHUNK-SERVO 的重新检索/伺服，或选择恢复 primitive。
- **接触段**：若当前步骤是“插入/挂/拧/拉拉链”等接触步骤，CHUNK-SERVO 在 30 步 chunk 内用 5 步伺服块；不改变 API 的 chunk 长度。
- **步骤完成**：进度头确认步骤完成后，允许 VLA 进入下一步；避免“重复抓取”或“提前放置”。
- **安全**：进度头置信度低时不要硬切；保留原始 action chunk，只做监控。

### 5.4 伪代码

```python
# Training
for batch in loader:
    obs, lang, action, step_label, next_text, grnd_mask = batch
    feat = vlm(obs, lang)
    pred_action = action_head(feat)
    loss = action_loss(pred_action, action)
    loss += 0.1 * progress_ce(progress_head(feat), step_label)
    loss += 0.05 * infonce(next_subgoal_head(feat), text_embed(next_text))
    loss += 0.05 * dice(grounding_head(feat), grnd_mask)
    loss += 0.05 * consistency(pred_action, action_head(vlm(aug_obs, lang)))
    loss.backward()
```

```python
# Inference (inside get_action)
feat = vlm(obs, lang)
action = action_head(feat)
step_logits, step_progress = progress_head(feat)
if step_progress < cfg.stall_threshold and same_step_for_n_chunks >= 2:
    trigger_chunk_servo(reason="progress_stall", step=step_logits.argmax())
return action
```

- 相机：挑战赛 4 路（head_stereo_left/right、wrist_left/right）；辅助数据若缺路，按模型支持选主视角 + 双腕，缺失用黑图/掩码，不要伪造。
- 状态/动作：统一到挑战赛 `meta/info.json` 的键；缺失键用 mask，不填 0 当真实值。
- 语言：保留原始指令；辅助任务的语言用于语言多样性，不要映射成挑战任务指令。
- 控制模式：只混 `joint` 或 `ee` 中与 WLA 配置一致的数据；不要混不同控制空间。

### 6.3 采样与训练

- 挑战:辅助 = **70:30**（先小规模 90:10 试）。
- 任务平衡：按任务采样温度 `τ=0.5–1.0`，避免大任务淹没小任务。
- 训练：冻结 VLM，只训 action head + state projector；辅助数据只加 action loss，不加步骤头（步骤标签仅挑战任务有）。
- 评估：挑战 held-out 任务/物体/背景；若掉 >2pp，降低辅助比例或停。

## 7. WLA 微调配方

### 7.1 基础配置

| 项 | 建议 |
|---|---|
| 基座 | `UnifoLM-WLA-1.0-Base`（6B） |
| 冻结 | VLM backbone（`trainer.freeze_modules: qwen_vl_interface`） |
| 训练 | DiT action head + robot-state projector；可选 LoRA（rank 16–32） |
| 精度 | bf16；梯度检查点 |
| 卡 | 单卡 24GB 可跑；建议 2–4 卡 40–80GB 加速 |
| batch | 32–64（按显存） |
| action chunk | 30（WLA 默认 @30Hz）；提交时按 API 固定值 |
| 图像 | 480×640；按 WLA 相机配置选路 |
| 优化器 | AdamW；action head lr 1e-4；LoRA lr 1e-5；cosine |
| 步数 | 20k–50k；早停看 held-out action loss |
| 数据 | 原图:合成 ≥1:1；轴平衡采样；挑战:辅助 = 70:30 |

### 7.2 损失组合

```text
L = L_flow_action
  + 0.05 * L_consistency        # 仅 observation-only 增强
  + 0.10 * L_progress           # 仅挑战任务有步骤标签
  + 0.05 * L_subgoal
  + 0.05 * L_grounding
```

- 若显存/时间不足，先只加 `L_consistency`；STEP-GRAPH 作为第二阶段。
- 不要在多视角不一致的增强上算 consistency；先过 G1。

### 7.3 训练数据划分

- 按 **session/物体/背景** 分组划分，不按相邻帧随机划分（避免泄漏）。
- held-out：每任务留 10–15% episodes；再留 2–3 个任务做“任务级 held-out”（只用于评估，不训练）。
- 增强变体只从训练 split 生成；验证/测试 split 不增强。

## 8. 评测协议

### 8.1 离线/仿真门 G0–G3

| 门 | 内容 | 通过线 |
|---|---|---|
| G0 | 32 任务 schema 完整；5 轴映射；试点任务选定 | 32/32；3+2 任务 |
| G1 | 增强质量（分割/深度/重投影/仿真/人工） | §4.4 |
| G2 | 动作保真 + 轴增益 | §4.4 |
| G3 | 步骤头准确率/时间 IoU | step acc >80%；temporal IoU >0.7 |

### 8.2 单任务通道 A/B（真机）

- 任务：T01、T21、T25（第一波）；T09、T16（第二波）。
- 每组 10 次（单任务通道上限）；配对/随机化顺序；记录成功、步骤分、失败原因、恢复次数。
- 基线：官方 WLA 微调（同数据、同训练步数）。
- 变体：
  - B1：+2D 轴；
  - B2：+2D+3D 轴；
  - B3：+STEP-GRAPH；
  - B4：+CHUNK-SERVO；
  - B5：全栈。
- **继续条件**：至少 2 个任务 +2 次成功，或步骤分 +5；否则缩回 2D/单栈。
- **注意**：10 次标准误大（p=0.5 时约 15.8pp）；不要用单任务一次涨跌下结论；用 5 任务合并 + bootstrap。

### 8.3 全 32 任务 dry run

- 若拿到评测资格：10 次/任务；记录分轴成功率（位置/干扰/背景/未见/人扰）。
- 目标：总平均成功率 baseline +3pp；无任务掉 >5pp；步骤分 +3。
- 若无法全量：用 5 任务单任务通道 + 离线代理 + 仿真代理，不假装全量。

### 8.4 延迟/合规

- 端到端 `get_action` < **0.5s/chunk**（含网络）；180s/run 预算。
- 单模型：不加载第二个大模型；辅助头在同一进程/同一权重内。
- 端口：N 个连续端口从 8765；每端口 `reset()` 隔离。
- 日志：记录每 chunk 的进度/触发/恢复，便于复盘。

## 10. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 合成伪影/域 gap | 高 | 中 | 原图:合成 ≥1:1；G1/G3；人工抽检；先 2D |
| 动作标签错误 | 中 | 高 | 相对位姿重定向；仿真可行性；拒绝坏样本 |
| 透明/反光/可变形失败 | 高 | 中 | 只做 2D；不强行 3D；任务白名单 |
| 3D 重建/渲染算力大 | 中 | 中 | 3 任务全量、32 任务 20%；2D 先行 |
| 步骤标签噪声 | 高 | 中 | 置信度过滤/ignore；人工抽检；软标签 |
| 进度头误导触发 | 中 | 中 | 高置信才触发；保留原 action；A/B |
| 单任务 10 次方差大 | 高 | 高 | 5 任务合并；配对；bootstrap；离线代理 |
| 外部数据不许可 | 中 | 中 | 只用官方数据 + 派生；许可确认前不混 |
| 榜单合成误导 | 高 | 中 | 不用榜单排任务；用官方 difficulty/单任务通道 |
| 单模型合规 | 低 | 高 | 所有头在同一权重；无在线第二模型；代码审计 |

## 11. 合规清单

- [ ] 32 任务同一模型；无 per-task 权重切换。
- [ ] 无在线第二模型/LLM；进度/grounding 头属于同一模型。
- [ ] 自部署；N 端口从 8765；`reset()` 隔离。
- [ ] 不假设 depth/force/tactile；只用 API 提供的观测。
- [ ] 外部数据/3D 资产许可已确认；文档记录来源。
- [ ] 增强数据不包含评测集/测试集泄漏；按 session/物体/背景划分。
- [ ] 不通过榜单/单任务通道过拟合；保留 held-out。
- [ ] 提交前跑一遍 example policy 接口兼容性测试。
