## 1. 直觉与动机（两个灵感的碰撞）

### 直觉 1（动力学 → 真正的失败模式是「动作不可执行」，不是「动作不对」）

上一轮我们把注意力放在「数据从哪来、分布怎么覆盖考纲」。但真机评测里还有一类损失被低估：**策略输出的动作在几何上是对的，在动力学上却不可执行**。遥操作示教本身是高 jerk 的（F23：jerk p99≈600–900 rad/s³），而评测时的推理延迟、动作分块执行、机器人关节限速/限加速度、桌面接触，都会让「指令轨迹」和「实际轨迹」产生偏差。偏差一旦累积，表现为抓偏、推不动、插不进、物体被带飞——看起来像「泛化失败」，其实是「动力学不可行」。更关键的是：我们**没有力/触觉通道**（F8），所以无法直接感知接触；但「指令与下一步状态之差」提供了一个稀疏而高精度的残差信号（F24），可以在接触/饱和发生时触发恢复，而不必假装有六维力传感器。

### 直觉 2（人形机器人 → 这是一个站在桌前的 29-DoF 人形，不是固定基座机械臂）

接口里一直躺着一条被忽略的通道：`action.pivot`（F20）。它不是装饰——官方 WBC 部署代码确实从全身动作里推导它（F21），训练数据也确实带 `action.pivot / action.base_command / action.waist_action_joint / action.lower_body` 标签（F22）。但 32 任务的统计揭示了一个反直觉事实：**pivot 在示教里几乎是任务级常数**——base 速度≈0、yaw/roll≈0、height≈0.73–0.74，只有 pitch 在 0.113–0.214 之间按任务取少数几个值。也就是说，人形在桌面前采用的是「固定站姿 + 前倾腰 + 固定高度」的准静态操作，而不是边走边做。**如果策略把 pivot 全零输出（参考 example 就是这样），而评测器又真的消费 pivot，那么它命令的是一个与示教完全不同的站姿（height=0, pitch=0），会系统性地改变工作空间与相机视角。** 这是一笔「若被消费则高收益、若被忽略则零成本」的不对称赌注。

### 直觉 3（二者碰撞 → pivot 是被人形姿态先验锁住的低维通道，动力学护栏是它的安全壳）

把两个灵感叠在一起，得到一个很干净的图像：

- **人形姿态先验**（I10）回答「身体该以什么姿态站在桌前」：从 32 任务示教里提取每个任务的 `pivot`/`waist`/`lower_body` 常数或低维流形，推理时直接复用；它几乎不增加算力，却把「人形站姿」从策略的自由变量变成一个受控先验。
- **动力学包络护栏**（I11）回答「这条动作 chunk 能不能被这台人形执行」：用示教统计出的速度/加速度/工作空间/自碰撞包络，加上「指令-状态残差」触发，对动作做时间缩放或拒绝，而不是逐关节硬裁剪。它不改变模型权重，是 PolicyService 内的后处理。

**三者统一**：上一轮说「中期胜负手在数据引擎」；这一轮补上后半句——**数据引擎决定策略「想做什么」，人形姿态先验与动力学护栏决定这些意图「能不能在这台 29-DoF 人形上落地」。** 前者是分布问题，后者是执行问题；在真机步骤分制下，执行问题会直接吞掉分布收益。

## 2. 严谨定义（先直觉，后定义）

### 2.1 全身操作 MDP

把 challenge 的一步交互写成

```
s_t = (I_t, l, q_t^arm, q_t^grip, q_t^lower, e_t^L, e_t^R)
a_t = (a_t^arm, a_t^grip, a_t^pivot)
```

其中 `I_t` 是 4 路图像，`l` 是语言指令，`q_t^lower` 是 15 维下身本体感知，`e_t^L/R` 是 base 系 EE 位姿；`a_t^arm` 在 joint 空间是 7 维目标关节，在 ee 空间是 6 维绝对位姿；`a_t^pivot = [vx,vy,vw,yaw,pitch,roll,h]`。评测器按 chunk 执行 `a_{t:t+T_a}`，每步记录延迟与动作统计（README §6），所以「动作是否平滑、是否统计正常」本身也是可信度的一部分。

### 2.2 人形姿态流形

对任务 `k`，从示教中取 pivot/waist/lower_body 的样本，定义任务姿态先验

```
M_k = { μ_k^pivot, Σ_k^pivot; μ_k^waist, Σ_k^waist; μ_k^lower, Σ_k^lower }
d_k(a) = ||a^pivot - μ_k^pivot||_{Σ_k^{-1}} + λ_w ||a^waist - μ_k^waist||_{Σ_k^{-1}}
```

F22 的统计说明 `Σ_k^pivot` 很小（height std≈0.01–0.016，pitch 在多数任务内近似常数），所以 `M_k` 可以先用「每任务一个常数向量」近似；这正好是最小可行版本。**关键不是学一个复杂的全身策略，而是先证明「不输出零 pivot」比「输出零 pivot」更接近示教分布。**

### 2.3 动力学包络与可行集

对任务 `k`，从示教统计出关节级包络

```
E_k = { (q̇, q̈, e) :
        q̇_j ∈ [q̇_j^{lo}, q̇_j^{hi}],      # 例如 p0.5–p99.5
        q̈_j ∈ [q̈_j^{lo}, q̈_j^{hi}],      # 例如 p0.5–p99.5
        e ∈ W_k,                          # EE 工作空间凸包/椭球
        dist(e_L, e_R) ≥ d_k^{min},       # 双臂自碰撞代理
        jerk ≤ J_k^{max}                  # 分速度档位，避免误裁快动作
      }
```

给定策略输出 `a`，护栏是一个投影/修复算子

```
G_k(a) = argmin_{a' ∈ E_k} ||a' - a||_2^2
```

实现上不做逐维硬裁剪（会破坏几何路径），而是优先**整段 chunk 时间缩放** `a'(t) = a(αt)`，`α>1` 降速，直到速度/加速度落回包络；若工作空间或自碰撞仍不满足，再做小幅平移/分离偏置或拒绝该 chunk 并请求重规划。这样既保留示教的几何形状，又把动力学可行性拉回分布内。

### 2.4 接触/饱和残差

定义

```
r_t = || a_t^arm - q_{t+1}^arm ||_∞
trigger_t = 1[ r_t > τ_k  for  m  consecutive steps ]
```

F24 给出 `τ_k ≈ p99.5`（约 0.12–0.15 rad）、`m=2` 时是「高精度、低召回」的事件检测器。它的正确用法不是「当力传感器用」，而是：

- 检测到 `trigger` → 判定当前处于接触/饱和/被物体阻挡阶段；
- 在该阶段切换更保守的 chunk（短 chunk、降速、保持夹持），或调用 I5 的恢复示教；
- 在自由空间阶段则恢复正常速度。

这比「无条件短 chunk」更省时间预算，也比「无条件长 chunk」更安全。

### 2.5 目标函数

把任务进度、姿态先验、动力学可行性、平滑性写在一起：

```
J(π) = E[ progress ] - λ_M E[d_k(a)] - λ_E E[1(a ∉ E_k)] - λ_J E[jerk(a)]
```

I10 主要优化 `λ_M` 项，I11 主要优化 `λ_E, λ_J` 项；两者都不改主干 VLA 的权重，属于推理期「姿态-动力学双闸」。

## 3. 对第 2 轮痛点的增量修订

- **P1（单模型平均分被最弱任务支配）**：弱任务往往也是「姿态/工作空间最别扭」的任务（如 OrganizeTools 的 pivot pitch=0.214），I10 的任务级姿态先验对弱任务收益更大。
- **P2（泛化缺口）**：视觉增广已由 I1 覆盖；本轮新增「动力学级增广」（时间重参数化）作为第二条泛化轴——它改变速度/加速度分布，不改变几何，能提升对评测延迟和执行速度的鲁棒性。
- **P4（无触觉）**：F24 的残差触发是第二条缓解路径；它是稀疏事件信号，不是密集力感知，避免过度承诺。
- **P5（时间压力）**：I11 的「接触阶段短 chunk / 自由空间长 chunk」比 I4 的手部检测更直接；两者可并联。
- **P7（先手窗口）**：F22/F23/F24 都是用公开 `meta/stats.json` 与一个小 parquet 就能算出的先手信息，社区尚未见系统化使用；先手复利仍在。
- **P8（示教质量）**：新增「动力学质量分」——jerk、包络越界率、姿态偏离度、残差尖峰；与进度效率、平滑度一起做 per-episode 加权。
- **新增 P9（人形姿态错配）**：若评测器消费 pivot，零 pivot 与示教站姿系统性不一致；这是「接口默认值陷阱」。
- **新增 P10（动力学不可行）**：高 jerk 示教 + 评测延迟 + 接触，会让几何正确的动作在执行层失败；需要数据驱动的包络，而不是教科书限幅。

## 4. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

## 7. 本轮最大风险

**一句话**：I10 与 I11 都建立在一个尚未被官方文档确认的前提上——`action.pivot` 真的被评测器消费、且训练数据的「常数 pivot」语义与部署适配器的「waist→pivot」推导一致；如果语义判错，姿态先验可能从「修站姿」变成「制造跳变」，而动力学包络也可能把合法的快速接触动作误裁掉，因此必须先做 pivot 语义核实与 L0 包络校准，再上真机。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I10 人形姿态先验与 pivot 通道校准（新） ★★★★★

- **动机**：challenge 的动作契约里有一个强制共享通道 `action.pivot [7] = [vx,vy,vw,yaw,pitch,roll,height]`，但参考实现输出全零；而 32 任务示教的 pivot 是任务级近似常数：`vx/vy/vw/yaw/roll≈0`，29/32 任务 `pitch=0.150`，`height≈0.738`（F22）。如果评测器消费 pivot，零值命令的是与示教完全不同的站姿（height=0、pitch=0），会系统性改变工作空间、相机视角与可达性；如果评测器忽略 pivot，输出任务先验也无害。这是一个**低风险、非对称收益**的修正。
- **与现有方案差异**：直接 SFT/零动作基线把 pivot 当摆设；本点把「人形站姿」从策略自由变量变成任务级先验，并把它与 waist/lower_body 的本体感知绑定。
- **技术可行性**：极高。仅用各任务 `meta/stats.json` 的 `action.pivot` 均值即可生成先验表（已生成，见 §2.1），无需下载完整数据；推理时一次查表 + 常数填充，成本≈0。
- **所需资源**：0 GPU；1 人日工程；一次 L0 对照与一次真机抽测。
- **落地步骤**：
  1. 生成 32 任务 pivot 先验表（已完成，§2.1）；
  2. 在 PolicyService 里按 `observation.language`/任务名查表，输出 `action.pivot` 常数块；
  3. 用首帧 `observation.state.lower_body` 做「相对偏移」校准：若观测到的 waist/height 与先验差异过大，则在 chunk 内线性 ramp 到先验，避免跳变；
  4. L0 对照：零 pivot vs 任务先验 vs 观测自适应；
  5. 真机抽测 3 任务（含 OrganizeTools 的 0.214 例外）。
- **风险**：pivot 语义未官方文档化（F21 vs F22 的语义不一致）；若评测器把 pivot 当绝对目标，错误先验会造成站姿跳变。缓解：先核实语义；默认用「ramp + clip」而不是硬跳；保留零 pivot 作为可切换 fallback。

### I11 数据驱动动力学包络护栏（新） ★★★★★

- **动机**：真机失败常常不是「动作方向错」，而是「动作不可执行」——遥操作示教本身高 jerk（F23：jerk p99≈600–900 rad/s³），评测延迟、chunk 执行、关节限速/限加速度、桌面接触会让指令轨迹与实际轨迹偏离。我们没有力/触觉通道（F8），但「指令-下一步状态」残差是稀疏、高精度的接触/饱和事件信号（F24）。
- **与现有方案差异**：常规做法是逐关节硬裁剪或固定短 chunk；本点用**示教分位数**校准速度/加速度/工作空间/自碰撞包络，优先用**整段 chunk 时间缩放**修复（保留几何路径），并用残差触发在接触态降速、自由态恢复长 chunk。它是 PolicyService 内的后处理，不改权重、不引入第二个学习策略。
- **技术可行性**：高。统计脚本只需 parquet + numpy；推理期检查 O(T_a·J)，J≈14，T_a≈8–16，远小于 66ms 预算。
- **所需资源**：1×CPU 即可做离线统计；1 人周工程；无需 GPU。
- **落地步骤**：
  1. 在 32 任务留出 episode 上统计每关节速度/加速度/jerk 的 p0.5/p99.5，EE 工作空间椭球，双臂最小距离分布；
  2. 实现 `DynamicsEnvelope` 与 `time_scale_repair`；
  3. 实现残差触发器 `r_t = ||a_t^arm - q_{t+1}^arm||∞`，阈值取 p99.5，连续 2 步触发；
  4. L0：在留出集上测越界率下降、路径保真度、误裁率；
  5. 真机：接触任务（PlugCharger/ZipUp/PourOutMedicine）A/B。
- **风险**：包络过紧会误裁合法快速接触动作；残差触发召回低，不能当密集力传感器。缓解：分速度档位设 jerk 上限；只对「连续 2 步 + 多关节」触发；先用 L0 的「越界率 vs 真机失败率」相关性验证。

- **v1.1 保留**：按官方考纲校准 5 轴视觉/场景增广（位置、干扰物、背景、未见物品、指令/布局），把零样本泛化转成分布内泛化。

## 1. 关键事实与推导

### 1.1 pivot 的「常数站姿」现象（F22）

对 32 个任务逐个读取 `meta/stats.json`，`action.pivot` 的均值呈现极强的规律：

| 组 | 任务 | pivot pitch | height |
|---|---|---:|---:|
| 默认 | 其余 29 个任务 | 0.150 | 0.727–0.740 |
| 例外 | FoldTowel | 0.120 | 0.735 |
| 例外 | StorePaddle | 0.113 | 0.737 |
| 例外 | OrganizeTools | 0.214 | 0.736 |

`vx/vy/vw/yaw/roll ≈ 0`；`pitch` 在任务内 std≈0.009–0.06，`height` std≈0.002–0.016。ZipUp 的原始 parquet 进一步确认：同一 episode 内 pivot 逐帧完全相同（frame 0/128/256/512 均为 `[0,0,0,0,0.15,0,0.74]`），而 `waist_action_joint` 独立变化（yaw/roll/pitch 有真实轨迹）。**结论：训练数据的 pivot 更像「任务级基座/躯干设定点」，不是逐帧全身轨迹；这与官方部署适配器「从 waist 推导 pivot」的语义并不一致，是本轮最优先的核实项。**

### 1.2 动力学包络的示教统计（F23/F24）

ZipUp 369 eps / 131,972 帧，30fps：

| 指标 | 左臂 p99 | 左臂 p99.9 | 右臂 p99 | 右臂 p99.9 |
|---|---:|---:|---:|---:|
| \|关节速度\| (rad/s) | 1.02 | 2.03 | 1.62 | 2.65 |
| \|关节加速度\| (rad/s²) | 13.1 | 32.1 | 19.5 | 41.4 |
| \|jerk\| (rad/s³) | 596 | 1644 | 934 | 2129 |
| 指令-下一步状态残差 (rad) | 0.064 | 0.118 | 0.090 | 0.149 |

- 教科书式 `|vel|≤1 rad/s` 会裁掉约 1.05%（左）/4.52%（右）的帧；`|acc|≤20 rad/s²` 会裁掉 0.34%/0.93%。所以包络必须用**示教分位数**校准，而不是拍脑袋。
- 残差 >0.2 rad 的帧仅 0.05–0.09%，但出现在 3.5%/8.1% 的 episode 中——适合做高精度事件触发，不适合做密集接触估计。

```python
def pivot_chunk(task_name, T, observed_height=None, ramp=8):
    pitch, height = PIVOT_PRIOR.get(task_name, (0.150, 0.738))
    target = np.array([0, 0, 0, 0, pitch, 0, height], dtype=np.float32)
    out = np.tile(target, (T, 1))
    if observed_height is not None and ramp > 0:
        # 仅做“相对偏移 + 线性 ramp”，避免绝对目标造成站姿跳变；
        # observed_height 的来源（lower_body 的哪一维 / 是否需要正运动学）
        # 必须在核实 pivot 语义后确定。
        start = target.copy()
        start[6] = float(np.clip(observed_height, 0.60, 0.80))
        for i in range(min(ramp, T)):
            alpha = (i + 1) / ramp
            out[i] = (1 - alpha) * start + alpha * target
    return out
```

> 说明：`observed_height` 的具体来源取决于 pivot 与 lower_body 的真实映射；在语义核实前，建议先只用常数先验（不 ramp），并保留 `USE_PIVOT_PRIOR` 开关。

### 2.2 数据驱动动力学包络与时间缩放修复

```python
class DynamicsEnvelope:
    def __init__(self, task_name, stats):
        s = stats[task_name]
        self.v_lo, self.v_hi = s["vel_q005"], s["vel_q995"]     # per joint
        self.a_lo, self.a_hi = s["acc_q005"], s["acc_q995"]
        self.ee_center, self.ee_prec = s["ee_mean"], s["ee_prec"]  # workspace ellipsoid
        self.d_arms_min = s["arm_dist_q05"]
        self.jerk_hi = s["jerk_q99"]

    def violations(self, q_arm, a_chunk, dt=1/30):
        # a_chunk: (T, 14) absolute joint targets.
        # 注：workspace/self_collision 两项假设已把 chunk 转成 EE 轨迹；
        # 若策略在 joint 空间，需要先做 FK（可用数据驱动 FK 近似）。
        v = np.diff(np.vstack([q_arm, a_chunk]), axis=0) / dt
        acc = np.diff(v, axis=0) / dt
        jerk = np.diff(acc, axis=0) / dt
        out = {}
        out["vel"] = np.mean((v < self.v_lo) | (v > self.v_hi))
        out["acc"] = np.mean((acc < self.a_lo) | (acc > self.a_hi))
        out["jerk"] = np.mean(np.abs(jerk) > self.jerk_hi)
        out["workspace"] = np.mean(self._mahalanobis(a_chunk[:, :3]) > 3.0)
        out["self_collision"] = np.mean(self._arm_dist(a_chunk) < self.d_arms_min)
        return out

    def repair(self, q_arm, a_chunk, max_alpha=2.0):
        alpha = 1.0
        while alpha <= max_alpha:
            scaled = self._time_scale(a_chunk, alpha)
            if max(self.violations(q_arm, scaled).values()) < 0.01:
                return scaled, alpha
            alpha *= 1.15
        # 仍不可行：返回原 chunk，由上层降速/短 chunk/重规划
        return a_chunk, None

    @staticmethod
    def _time_scale(chunk, alpha):
        T = len(chunk)
        t = np.linspace(0, T - 1, int(np.ceil(T * alpha)))
        return np.stack([np.interp(t, np.arange(T), chunk[:, j])
                         for j in range(chunk.shape[1])], axis=1)
```

### 2.3 残差触发与接触态策略

```python
class ContactResidualTrigger:
    def __init__(self, tau=0.13, m=2):
        self.tau, self.m = tau, m
        self.count = 0

    def update(self, a_arm, q_next_arm):
        r = float(np.max(np.abs(a_arm - q_next_arm)))
        self.count = self.count + 1 if r > self.tau else 0
        return self.count >= self.m          # True: 接触/饱和/被阻挡
```

### 2.4 动力学级增广：时间重参数化

```python
def time_warp_episode(ep, s):
    """保持几何路径，仅改变时间轴；s>1 变慢，s<1 变快。"""
    T = len(ep["action.left_arm"])
    t_src = np.arange(T)
    t_dst = np.linspace(0, T - 1, int(round(T * s)))
    out = {}
    for k, v in ep.items():
        if k.startswith(("action.", "observation.state.")):
            out[k] = np.stack([np.interp(t_dst, t_src, v[:, j])
                               for j in range(v.shape[1])], axis=1)
    return out
```
