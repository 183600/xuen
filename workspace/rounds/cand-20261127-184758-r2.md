**关键推论（本轮立论起点）**：官方把「大 VLM + 大 DiT + 多源数据」都开源了，所以单纯再堆一个更大模型既没有先手也不符合预算；真正的空位是**如何把多源能力压进一个 24GB、15Hz、单服务的在线学生**。这正是「技术融合 × 轻量化设计」的交点。

## 1. 直觉与动机（两个灵感的碰撞）

### 灵感 1（技术融合 → 官方给了三套可融合资产，但融合的成本被藏起来了）

直觉：第 2 轮把「数据」当主战场；技术融合视角下，可融合的不止数据，还有**模型、模态与技术栈**：WLA 策略（在线）、WMA-0 世界模型（离线合成/前瞻）、Isaac Lab 仿真（离线验证）、110 语料（离线教师）、4 路 RGB + 本体 + 语言 + 历史（在线多模态）、检索先验（reset 期）、恢复示教（离线）。把它们全部并联到推理期很诱人，但每条融合都暗含成本：显存、p99 延迟、负迁移、集成复杂度、单模型边界风险。

严谨定义：设在线策略为单服务 \(f_\theta\)，其单步成本三元组 \(c(f)=(\text{compute}, \text{latency } L, \text{memory } M)\)，预算 \(L_{p99}\le 40\text{ms}\)（15Hz 参照，F12）、\(M\le 24\text{GB}\)、端口数 \(N\)。融合算子 \(\mathcal F\) 把源集合 \(S_1..S_k\) 合成能力增益 \(\Delta Q\)；轻量化算子 \(\Lambda\) 把成本降到 \(c'\)，同时引入质量损失 \(\Delta Q_{\text{loss}}\)。融合可准入当且仅当

\[
\Delta Q_{\mathcal F}-\Delta Q_{\text{loss}}>0,\qquad c(\Lambda(\mathcal F))\le c_{\text{budget}}.
\]

定义**融合效率** \(\eta=(\Delta Q_{\mathcal F}-\Delta Q_{\text{loss}})/\Delta c\)。低于预算闸的融合，只能以「离线教师/离线数据」形态存在，不能进计分通道。

核心反直觉点：**融合的正确位置不在推理期，而在训练期；在线看到的应当是一个被融合「教过」的轻量学生，而不是一支融合「拼起来」的舰队。**

### 灵感 2（轻量化设计 → 预算不是优化项，而是准入条件）

直觉：本赛的硬约束异常清楚：默认单卡 24GB（F22）、15Hz/66ms 量级（F12）、N 端口共享后端、动作头 4 步去噪（F22）、指令每集固定（F18）。轻量化不是「有空再压一压」，而是决定一个想法能不能上场的门槛。轻量化有四条正交路径：(a) **数据轻**——核心集/去重/难度采样，减少 110 语料的体量与负迁移；(b) **参数轻**——LoRA/adapter、动作头瘦身、量化；(c) **计算轻**——reset 期缓存、任务族路由、单路径激活、CUDA Graph；(d) **集成轻**——把多模块守卫压成一个轻量路由器，而不是并联多模型。

严谨定义：轻量化是一个保序映射 \(\Lambda\)，在给定质量保留率 \(\rho=Q(\Lambda(T))/Q(T)\) 下最小化在线成本；本赛要解的是带约束的多目标问题

\[
\max_{\Lambda}\ \rho(\Lambda)\quad \text{s.t.}\quad L_{p99}(\Lambda)\le L_0,\ M(\Lambda)\le M_0,\ \text{单服务边界}.
\]

「轻」不等于「小模型」：在 VLM 冻结（F22）的结构下，**缓存与路由带来的延迟收益往往大于换小模型**，因为每步真正贵的是重复计算每集不变的东西。

核心反直觉点：**最有效的轻量化，是识别「哪些计算每集只该做一次」——语言嵌入、任务族选择、检索先验都该在 reset 期算完并缓存，而不是每步重算。**

### 统一命题：融合-轻量化对偶（Fusion–Lightweight Duality）

技术融合回答「能力从哪来」，轻量化回答「能力以什么代价上线」。二者不是取舍，而是**分工**：离线尽可能融合（多源教师、世界模型、仿真、合成恢复），在线只保留一个学生 + 一个轻量路由器 + 一份 reset 缓存。第 2 轮的结论「中期胜负手在数据引擎」在本轮升级为：**胜负手在「数据引擎 → 学生」的蒸馏/压缩效率**；谁能用 20% 的数据与 1 个学生保住 90% 的融合增益，谁就同时赢下泛化与延迟。

## 2. 对第 2 轮痛点与风险的增量修订

- **R2 最大风险（110 语料淹没/负迁移）→ 用 I10 核心集正面拆解**：不再「先下载 1–2TB 再靠权重压」，而是先按「任务×技能×物体×场景×相机」覆盖选 15–25% 核心集，再共训。数据体量与负迁移风险同时下降。
- **P8（示教质量）**：轻量化视角下，质量加权应与核心集选择合并为一次「数据预算分配」，避免两套采样器互相打架。
- **P6（延迟/部署）**：从「事后优化」提升为「准入约束」；I6 增加预算账本与 reset 缓存，任何新模块必须申报在线成本。
- **I7（世界模型测试时前瞻）**：本轮明确降为**裁撤候选**——WMA-0 视频扩散的在线成本与 66ms 预算量级不符；其价值全部转入离线（I5 合成、I10 多样性、I8 验证）。
- **P7（先手窗口）**：轻量化让「1 人 1 卡」也能完成一轮完整消融，先手复利更实际。

## 3. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

- **Q9（融合可压缩性）**：110 语料 + 增广 + 合成恢复的融合增益中，核心集 + 蒸馏能保留多少？即质量保留率 \(\rho\) 随数据比例/学生容量的曲线，何时出现「剪掉长尾」的拐点？
- **Q10（多教师冲突）**：名义、孪生、增广、恢复、检索五个教师的行为在多处冲突（如「继续推进」vs「回退重抓」）；如何用能力条件/任务族路由把冲突显式化，而不是让蒸馏平均成四不像？
- **Q11（轻量路由稳定性）**：能力路由在 chunk 边界的切换会不会造成抖动、延迟尖峰与新的失败模式？如何用滞回 + 预算约束给出可证明的切换上界？

## 4. 设计原则（新增 PR6/PR7，其余保留）

- **PR6 融合预算律**：任何技术融合必须同时申报「在线成本」与「轻量化补偿」；没有补偿方案的融合只能留在离线。与 PR5 数据杠杆律互补：PR5 管数据值不值，PR6 管能力上不上得去。
- **PR7 离线融合、在线轻量（Offline-Fuse, Online-Light）**：训练期允许任意多教师/多源/多模态融合；推理期只允许一个学生 + 一个轻量路由器 + reset 缓存，禁止在计分通道并联第二个策略或每步调用外部大模型。
- PR1–PR5 保留（第 1 轮 §4、第 2 轮 §4）。

## 8. 本轮最大风险（一句话）

## 1. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 资源 / 落地 / 风险）

### I10 核心集融合：用 20% 的数据保住 90% 的融合增益 ★★★★★（新）

- **动机**：第 2 轮最大风险是「110 语料体量淹没 32 任务 + 负迁移」（R2），且全量下载 1–2TB、缓存与训练成本都高。轻量化视角下，多源融合应先问「哪些样本是边际信息最大的」，而不是「能不能全下载再压权重」。
- **与现有方案差异**：v1.1 的 I2 是「全量孪生子集 + loader 加权 patch」；I10 前置一层**覆盖约束的核心集选择**，把「数据量」和「采样权重」两件事合并成一次预算分配，同时降低负迁移与存储成本。
- **方法**：
  1. **样本表示**：每个 episode（或技能段）编码为 \(z_i=[\text{DINOv2-small 多视角池化};\ \text{任务文本嵌入};\ \text{技能标签};\ \text{物体类别};\ \text{相机配置}]\)，归一化。
  2. **覆盖目标**：在候选全集 \(V\) 上选子集 \(S\)，最大化设施选址覆盖
     \[
     \max_{|S|\le B}\ \sum_{j\in H}\max_{i\in S}\ \mathrm{sim}(z_i,z_j)-\lambda|S|,
     \]
     其中 \(H\) 是留出探针集。该目标单调子模，贪心给出 \(1-1/e\) 近似。
  3. **按泛化轴配额**：对每任务 \(k\) 与每轴 \(a\in\{\text{位置},\text{背景},\text{干扰物},\text{未见物体},\text{指令}\}\) 要求至少 \(q_{k,a}\) 个代表；用拉格朗日/分层贪心满足配额。DiverseManip 作为「未见物体/场景多样性」的锚点优先入选。
  4. **比例扫描**：10% / 15% / 25% / 50% / 100%，选满足「覆盖 ≥ 全量 95% 且 L0 代理 Δprog 在 1% 内」的最小比例。
  5. **与质量加权合并**：最终采样权重 \(w_i\propto \text{覆盖边际增益}_i\times \text{质量分}_i\)，一次分配，避免 I2 的质量采样器与核心集采样器打架。
- **技术可行性**：高。嵌入 1 GPU 日；选择是 CPU 子模优化；只下载入选子集。
- **所需资源**：1×24GB 做嵌入；磁盘 300–500GB（而非 1–2TB）；选择脚本 3 人日。
- **落地步骤**：①在 32 任务内部先做「留一任务/留一物体」覆盖验证；②加入 110 语料候选池与 DiverseManip 锚点；③比例扫描 + L0 代理；④与 loader 加权 patch 联调；⑤家族级负迁移 L0。
- **风险**：核心集剪掉长尾（缓解：按轴配额 + 留出未见物体压力测试）；嵌入相似度 ≠ 下游有用性（缓解：用 1 个小型学生做 10% 数据预实验校验）；近重复孪生虚高覆盖（缓解：先做语义去重，再算覆盖）。

### I11 多教师融合蒸馏：把「舰队」压成「一个学生」 ★★★★★（新）

- **动机**：技术融合天然产生多个教师：名义（32 任务）、孪生（110 核心集）、增广（I1）、恢复（I5）、检索先验（I9）。若把它们各自作为在线模块并联，显存/延迟/冲突都不可接受；正确做法是**离线多教师、在线单学生**。
- **与现有方案差异**：v1.1 是「各模块各司其职」；I11 把「能力」与「部署形态」解耦：教师可以很多、很大、很慢，学生只有一个、要快。
- **方法**：
  1. **教师集合**：\(T_{\text{nom}}\)（32 任务全量）、\(T_{\text{twin}}\)（I10 核心集）、\(T_{\text{aug}}\)（I1 增广）、\(T_{\text{rec}}\)（I5 合成恢复）、\(T_{\text{ret}}\)（I9 检索先验）。教师可以是同一 6B 架构的不同数据/不同推理步数版本，避免维护多套代码。
  2. **扩散动作蒸馏**：学生动作头为 4 步去噪（F22）。在采样到的扩散时间步上匹配教师的**干净动作 chunk** 或**速度场**：
     \[
     \mathcal L=\mathcal L_{\text{BC}}+\alpha\mathcal L_{\text{KD}}^{\text{act}}+\beta\mathcal L_{\text{KD}}^{\text{feat}}+\gamma\mathcal L_{\text{rel}}.
     \]
     \(\mathcal L_{\text{KD}}^{\text{act}}\) 用教师更多步数（如 8–16 步）产生更干净的目标；\(\mathcal L_{\text{KD}}^{\text{feat}}\) 对齐 DiT 中间层；\(\mathcal L_{\text{rel}}\) 对齐 chunk 内动作两两距离，保留多模态结构。
  3. **冲突显式化**：给学生的动作头加一个**能力 token / 任务族嵌入**（与 I12/I13 共用），让「名义」与「恢复」教师监督不同条件模式，避免平均成四不像。同一状态下教师冲突时，用官方得分点（F17）离线打分选优，或训练一个小判别器。
  4. **可选瘦身**：把 DiT-L（16 层/1024）蒸馏到 DiT-M（12 层/768），VLM 仍冻结；以动作误差与 L0 代理为约束，测质量保留率 \(\rho\)。若收益不足，则保留 DiT-L，仅做能力蒸馏。
  5. **可撤模块**：I9 检索先验蒸馏进学生后，在线检索可降为可选（进一步省 10ms/集）。
- **技术可行性**：中-高。动作空间/特征/关系三类蒸馏都是成熟技术；难点在教师冲突与容量瓶颈。
- **所需资源**：教师离线训练 8×A100 80G（可租/可分阶段）；学生微调 1×24GB；总周期 3–4 周。
- **落地步骤**：①先做「单教师 → 学生」验证蒸馏管线；②加入第二教师，测冲突；③能力 token 条件化；④DiT 瘦身消融（可选）；⑤L0 保留率曲线 + L2 真机。
- **风险**：容量瓶颈导致教师能力丢失（缓解：先测 \(\rho\)-曲线，不达标就不瘦身）；教师标签噪声（缓解：只用通过得分点门禁的合成段）；蒸馏过拟合离线分布（缓解：L0 按轴压力测试 + 真机 top 候选确认）。

### I12 任务族 LoRA 专家融合：指令已知的免费路由 ★★★★（新）

- **动机**：语言指令每集固定（F18），任务身份在 reset 期就是已知的——这是一个免费的侧信道。用一个 LoRA 拟合 32 个差异极大的任务，容量被平均；为每个任务存 32 个 adapter 又浪费显存。折中是**任务族**（6–8 族）。
- **与现有方案差异**：v1.1 的 LoRA 是单适配器全局微调；I12 把「多专家融合」放在 reset 期，用任务族选择/合并实现「专精」，每步仍只有一个 adapter 生效。
- **方法**：
  1. **族划分**（初稿，LLM 初筛 + 人工校对）：抓放/搬运、插入/连接、倾倒/液体、折叠/布料、开合/旋转、堆叠/排列、分拣/传送、工具/收纳。
  2. **训练**：对每族在 DiT 动作头（可选 VLM）上训练 LoRA（r=8–16）；共享冻结基座。
  3. **reset 选择**：解析 `observation.language` → 族分类器（规则/小模型）→ 选 \(k\)；跨族任务用 TIES/DARE 合并 top-2，或按软权重 \(\alpha\) 加权：
     \[
     W=W_0+\sum_k \alpha_k B_kA_k,\quad \alpha\in\Delta,\ \|\alpha\|_0\le 1\ (\text{默认})\ \text{或}\ \le 2\ (\text{合并}).
     \]
  4. **在线成本**：与单 LoRA 相同（每步只走一个 adapter）；显存 \(K\times\) 小 adapter（每族约 20–50MB）。
  5. **与 I13 协同**：族信息也作为能力路由的先验特征。
- **技术可行性**：高。官方 LoRA 配置现成（F23），adapter-only checkpoint 小；族分类是简单文本分类。
- **所需资源**：1×24GB 训练（逐族串行即可）；adapter 存储 < 2GB；1 人周。
- **落地步骤**：①32 任务族划分与留一任务校验；②逐族 LoRA 训练；③reset 选择器；④TIES 合并对照（合并 vs 切换）；⑤L0 留一族测试 + 真机抽测。
- **风险**：族划分与真实技能边界不符（缓解：留一任务测试 + 允许跨族软合并）；adapter 间干扰（缓解：合并前做权重裁剪/TIES）；「单模型 + 多 adapter」边界需向组委会书面确认（**新增确认项**）。

### I13 轻量能力路由器：把并联守卫压成单路径 ★★★（新，探针）

- **动机**：I3（几何伺服）、I4（人手干预）、I5（恢复）若同时在线运行，既有延迟叠加，也可能给出互相冲突的动作。实际每个 chunk 只需要一种模式。
- **与现有方案差异**：v1.1 是「guard 栈」并联；I13 用 <1ms 的路由器在 chunk 边界**只激活一条路径**，把「融合」变成「稀疏选择」。
- **方法**：
  1. **特征**：进度头输出、手部检测、检索距离、候选动作分歧度、EE 速度/接触代理、任务族。
  2. **模式**：nominal / recovery / geometric-servo / hold-retreat。
  3. **策略**：先用可解释决策树/规则（零训练、可审计），再考虑 <1M 参数的小 MLP；切换需滞回 \(m\) 个 chunk。
  4. **目标**：
     \[
     g(x)=\arg\max_{m}\ U_m(x)-\lambda_{\text{switch}}\mathbf 1[m\ne m_{\text{prev}}],
     \]
     约束 \(L_{p99}\) 增量 < 2ms。
- **技术可行性**：中-高。规则版几乎零成本；学习版需要离线日志。
- **所需资源**：回放日志 + 1 人周；无需额外 GPU 推理。
- **落地步骤**：①收集 I3/I4/I5 的离线回放与触发标签；②规则路由；③滞回与延迟测试；④与并联栈对照；⑤决定是否学习化。
- **风险**：切换抖动/误判（缓解：滞回 + 低置信回退 nominal）；规则覆盖不足（缓解：保留手动降级开关）。

### I1 v3 考纲校准五轴增广（深化）

- **动机**：同 v1.1，泛化轴公开（F2/F17），增广是全局乘性收益。
- **本轮变化（轻量化）**：增广**只在离线做**；引入「增广核心集」——每轴每档只保留信息量最大的一小批增广样本，避免生成式重增广把训练集膨胀数倍。重增广（如 inpainting/WMA）只保留通过 L0 的轴，其余退化为轻量几何/颜色变换。
- **与现有差异**：v1.1 是「按考纲放量」；v3 是「按考纲 + 按预算放量」，增广也要过 PR6。
- **落地**：①32 张考纲卡；②每轴 3 档 + 增广核心集；③L0 剂量-响应；④只对过闸的轴放量；⑤轴间交互 2 档析因。
- **风险**：增广核心集漏掉边缘模式（缓解：按轴配额 + 留出轴压力测试）。

### I2 v3 数据引擎 2.0（深化）

- **本轮变化**：由「全量 110 语料孪生子集（1–2TB）+ loader 加权 patch + 质量加权」改为 **I10 核心集（300–500GB）+ loader 加权 patch + 质量加权** 三合一。先选数据，再压权重，最后调质量。
- **与现有差异**：v1.1 的 R2 风险（语料淹没/负迁移）在 v3 被前置拆解；训练与存储成本同步下降。
- **落地**：①I10 选核心集；②孪生表只对入选样本生效；③loader patch 单测（batch 内任务频率验证）；④质量加权与核心集权重合并；⑤族级 L0 负迁移。
- **风险**：核心集与加权叠加导致某些任务过采样（缓解：权重上限裁剪 + 频率监控）。

### I3 接触任务族关键点视觉伺服回退（维持，接入 I13）

- 六要素同 v1.0；本轮把它从「常驻并联」改为「由 I13 在接触/低置信时激活的单路径」，在线成本从「每步都算」降为「按需算」。
- **降级预案 I3'** 不变：若组委会裁定混合推理违规，改为训练时辅助监督（关键点作辅助标签），推理纯端到端。

### I4 人手干预感知门控 + 自适应 chunk（维持，接入 I13）

- 六要素同 v1.0；本轮把「手部检测 + 干预状态机」作为 I13 的一个模式（hold-retreat），而不是独立常驻模块。
- WMA-0 的 15Hz/horizon 16 参照（F12）继续用于 chunk 长度标定：干预态 4–6 步、稳定态 8–16 步。

### I5 v3 非标称示教合成 + 得分点对齐恢复（深化）

- **本轮变化**：合成数据（扰动重放/跨段缝合/WMA 续写）**只作离线教师**，经 I11 蒸馏进学生；在线不部署生成器、不增加模块。得分点（F17）继续做自动门禁。
- **与现有差异**：v1.1 的 I5 仍是「数据 + 进度头」；v3 明确其部署形态是「离线数据 → 蒸馏」，符合 PR7。
- **落地**：①得分点逆向；②3 个弱任务试点（PlugCharger/ZipUp/PourOutMedicine）；③合成段质量门禁；④作为 \(T_{\text{rec}}\) 教师参与 I11；⑤L0/L2。
- **风险**：合成分布失配（缓解：扰动幅度从考纲卡采样）；教师噪声（缓解：置信门控 + 人工抽检 5%）。

### I6 v3 确定性低延迟部署（深化，本轮最高优先级之一）

- **动机**：轻量化设计的主战场。官方结构已知：6B VLM 冻结 + DiT-L 16 层 × 4 步去噪（F20–F22），默认单卡 24GB。
- **本轮具体化**：
  1. **reset 缓存**（每集一次，F18）：语言嵌入、任务族选择（I12）、检索结果（I9）、初始状态统计；episode 内复用，避免每步重算指令。
  2. **共享 VLM、端口私有动作头**：VLM 前向可批处理多端口观测；DiT 动作头按端口并行/排队。
  3. **量化与编译**：VLM 尝试 fp8/INT8，DiT 保持 bf16（动作质量敏感）；`torch.compile` + CUDA Graph 固定形状。
  4. **adapter-only 加载**：LoRA 权重小几个数量级（F23），多端口共享基座。
  5. **相机子集**：按任务族选择 2–4 路相机（未验证前默认全 4 路），减少 VLM token。
  6. **预算账本**：每次提交记录 VLM forward、DiT 4 步、后处理的 p50/p99；p99 目标 < 40ms。
- **与现有差异**：v1.1 的 I6 是「部署工程清单」；v3 把它变成「有实测预算、有 reset 缓存、有 adapter 路由」的准入系统。
- **风险**：量化掉点（缓解：动作健康度 + L0 动作误差门禁）；VLM 前向仍超预算（缓解：相机子集 + 蒸馏/瘦身作为 fallback）。

### I7 世界模型测试时前瞻（降为裁撤候选）

- **本轮判断**：WMA-0 视频扩散的在线成本与 66ms/步量级不符；测试时 rollout 的前瞻收益未证，先裁撤在线路径。
- **资产去向**：WMA-0 仅保留离线用途——I5 合成恢复数据、I10 多样性增广、I8 的 L0 压力测试环境。裁撤不等于废弃。
- **复活判据**：仅当实测 p99 有 ≥2 倍余量且 L0 显示前瞻显著，才重新评估。

### I8 v3 评测运营闭环 + 分级消融注册表（深化）

- **本轮变化**：消融加入**成本轴**，从「单目标分数」升级为「分数-延迟 Pareto 前沿」。
- **L0（离线，免费）**：对留出集施加考纲轴偏移，代理指标 = Δprog + Δact + 关键点误差 + **覆盖率/保留率 \(\rho\)** + **p50/p99 延迟与显存**。
- **L1（低真机成本）**：\(2^{k-p}\) 部分析因，主效应优先；因子包括 {核心集比例, 蒸馏 on/off, 任务族 LoRA, 能力路由, 检索}。
- **L2（稀缺真机）**：只测 L0+L1 的 Pareto 前沿 top 2–3；判据：真机增益 ≥ 离线预测的 50%，且 p99 < 40ms。
- **注册表**：每条记录含 `offline_pred`、`real_gain`、`latency`、`memory`；滚动计算分层 Spearman；某代理相关性 >0.6 才可单独准入 L2。
- **风险**：成本轴让候选变多、决策变慢（缓解：先硬预算闸，再做 Pareto）。

### I9 v2 reset 期检索类比迁移（深化）

- **本轮变化**：为轻量化做三件事：①嵌入用 DINOv2-small 蒸馏版 + 乘积量化（PQ）/二值哈希，索引 < 0.5GB；②reset 检索 < 10ms；③检索先验可经 I11 蒸馏进学生，之后在线检索降为可选。
- **与现有差异**：v1.1 的 I9 是「DINOv2 + FAISS」；v2 是「可撤的轻量检索」。
- **风险**：PQ 量化损伤「同类不同外观」的细粒度（缓解：保留一个小的 float 重排层）；误检索（缓解：距离阈值 + 软先验 + L0 不伤标称）。

## 2. 关键伪代码

### 2.1 核心集选择（I10）

```python
def select_coreset(episodes, probe, budget_ratio, quotas):
    # episodes: [{id, task, skill, obj, scene, cam, emb, quality}]
    z = normalize([e.emb for e in episodes])
    B = int(len(episodes) * budget_ratio)
    S, gains = set(), {i: 0.0 for i in range(len(episodes))}
    # 分层贪心：先满足每任务/每轴配额，再最大化覆盖
    for (task, axis), q in quotas.items():
        pool = [i for i, e in enumerate(episodes) if covers(e, task, axis)]
        for _ in range(q):
            i = max((i for i in pool if i not in S),
                    key=lambda i: marginal_gain(i, S, z, probe))
            S.add(i)
    while len(S) < B:
        i = max((i for i in range(len(episodes)) if i not in S),
                key=lambda i: marginal_gain(i, S, z, probe))
        S.add(i)
    # 权重 = 覆盖边际增益 × 质量分（与 I2 合并）
    w = {i: marginal_gain(i, S - {i}, z, probe) * episodes[i].quality for i in S}
    return S, normalize_weights(w)

def marginal_gain(i, S, z, probe):
    return sum(max(sim(z[i], z[h]), max((sim(z[j], z[h]) for j in S), default=-1))
               for h in probe) / len(probe)
```

### 2.2 多教师融合蒸馏（I11）

```python
def distill(student, teachers, data, alpha=.5, beta=.1, gamma=.05):
    for batch in data:                      # batch 含 capability / task_family 条件
        cond = batch["capability_token"]
        with torch.no_grad():
            targets = [t.denoise(batch, steps=16, cond=cond) for t in teachers]
            target = resolve_conflict(targets, batch, scorer=official_steps)
        pred = student(batch, cond=cond)     # 4 步去噪
        loss = flow_matching(pred, batch["action"])
        loss += alpha * kd_action(pred, target)
        loss += beta  * kd_feature(student.hidden, teacher_hidden)
        loss += gamma * kd_relation(pred, target)
        loss.backward(); opt.step()
    # 可选：DiT-L -> DiT-M 瘦身；以 L0 动作误差 + 保留率 rho 为约束
```

### 2.4 轻量能力路由器（I13）

```python
MODES = ["nominal", "recovery", "servo", "hold"]

def route(feats, prev_mode, hysteresis=3):
    # feats: progress, hand_detected, retrieval_dist, action_disagreement,
    #        ee_speed, contact_proxy, task_family
    utility = {m: rule_or_small_mlp(m, feats) for m in MODES}
    best = max(MODES, key=lambda m: utility[m]
               - (0.0 if m == prev_mode else SWITCH_PENALTY))
    # 滞回：新模式需连续 m 个 chunk 占优才切换
    return stable_mode(best, prev_mode, hysteresis)
```

### 2.5 reset 缓存与部署（I6）

```python
class LightPolicyService:
    def reset(self, first_obs=None):
        self.lang_emb = self.vlm.encode_text(self.language)      # 每集一次
        self.adapter = reset_select_adapter(self.language, self.loras)  # I12
        self.prior   = self.retriever.search(first_obs) if first_obs else None  # I9
        self.mode    = "nominal"

    def get_action(self, obs):
        if self.lang_emb is None: self.reset(obs)
        # VLM 前向可跨端口批处理；DiT 4 步去噪每端口执行
        feat = self.vlm.encode_vision(obs, self.lang_emb)
        chunk = self.dit.sample(feat, steps=4, adapters=self.adapter)
        self.mode = route(self.features(obs, chunk), self.mode)  # I13
        return self.emit(chunk, self.mode)                       # 单路径
```
