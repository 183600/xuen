### 第 6 轮灵感驱动研究记录

**灵感词**：具身智能大模型、开源软件

**继承关系**：第 5 轮 CADVS-v5（IP-493~496，Certified Generative Execution）把提议从离散规则升级为条件流匹配 π_θ^FM，用证书不变性（定理 6）证明「提议可换、门不可换」，并加入记忆固化与情感调制，执行集 Exec_CADVS-v5 ⊆ Exec_CADVS-v4。但 v5 仍留三个未被触及的结构性短板：(a) 提议器是**单站自训练**的小流模型，跨具身/跨任务泛化受限于单站数据，且 R57「固化自指回路」缺少外部真值；(b) 证书是**站点私有**的，第三方无法复算，「门是信任边界」在社会层面退化为「相信门作者」；(c) 信任链（门代码/权重/依赖/构建产物）没有**供应链完整性**，v5 的「门冻结只读」在开源分叉与依赖投毒面前只是本地君子协定。两个灵感词统一为主题「开源可审计的具身基座执行」（Open Auditable Embodied Foundation Execution, OAEF），形成 CADVS-v6（IP-497~501）。本轮自律被**有意打破一次**：硬门从 7 增至 8，新增 kc_prov（来源/证明门）——理由是供应链完整性是七门在结构上看不见的新威胁类（门只能审轨迹，审不到「跑的是不是被审计过的那份门」）。执行集升级为 Exec_CADVS-v6 ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29。

**直觉与动机**：

1. **具身智能大模型 → 提议器从「单站流策略」升级为「冻结 VLA 基座 + 站点 LoRA 适配器」，但证书边界一寸不动**。直觉：与其每个站点从零学一个流策略，不如共享一个在海量跨具身数据上预训练的视觉-语言-动作（VLA）基座 B，站点只训练低秩适配器 A_i。定理 6（证书不变性）天然覆盖任意提议分布，所以 π_EFM 只是「又一个 π」——这把 v5 的「任意生成器 + 认证边界」真正落到一个工业级生成器上。但基座引入 v5 没有的三类风险：(i) **涌现能力**越出适配器已认证的技能包络 S_i；(ii) **权重投毒/后门**（基座可被植入触发式行为）；(iii) **版本漂移**（基座升级破坏已固化适配器）。应对：技能包络作为「提议支撑限制 + 密度新颖度」的软约束（不新增硬门，守住 v5 的锚点纪律）；基座-适配分离使「共享先验」与「本地证据」解耦；投毒交给第 3 点的供应链证明。关键洞见：**基座越强，越不能信；门必须比提议更保守**。

2. **开源软件 → 证书从「站点私有日志」升级为「可移植、内容寻址、可复算、可公开审计」的证书透明日志（PCT）**。直觉类比 TLS 的 Certificate Transparency（RFC 6962）：站点每签发一张执行证书，就把它（的承诺）追加进一个只增不改的 Merkle 日志，任何人可验证包含证明与一致性证明；站点之间 gossip，一旦某站点对不同审计者出示互相矛盾的日志（equivocation），即被检测。这把 v5-R57 从「只能内部红队缓解」升级为「外部可发现」：证书公开可复算，自洽但失真的自我背书会被第三方复算抓出。同时开源使门代码可被独立复现——**「可复现」是「可审计」的前提**，因此必须定义确定性与证书等价类（浮点非确定性、并行归约、GPU 噪声）。诚实边界：透明日志只证明「这份工件产出了这份证书」，不证明「门规范本身正确」。

3. **开源软件 → 供应链证明（SCAK）与「多眼审计」经济**。直觉：开源同时是**放大器**和**攻击面**——它让门可被独立复现（好事），也让恶意分叉可以「同证书格式、悄悄放松门」（坏事）。对策三层：SBOM + 签名发布 + 可复现构建哈希 + 远程证明，把「部署的门」绑定到「审计过的发布」；copyleft 使衍生门必须开源，把「分叉自由」约束为「分叉可见」；社区反例赏金（OCA）把「多眼」变成可计价的对抗审计。但 Linus 定律不是定理：多眼审计只是**经验覆盖**，故定理 11 只能给「覆盖度依赖」的界，不给根除保证。

**关键洞见**：v5 回答「提议=任意生成器、记忆反哺、人因含情感时，证书边界是否保持」；v6 回答「当提议来自一个**不可信、跨具身、可能被投毒**的开源基座，且证书必须被**外部第三方复算与审计**时，信任如何从『相信作者』升级为『验证工件』」。v5 的证书不变性只保证「门谓词与提议无关」，**不保证门工件与运行工件可信**；v6 把信任边界从轨迹层扩展到工件层/供应链层。唯一新增硬门 kc_prov 把「来源不可信」变成 fail-closed；其余七门、阈值 τ^5、调制 γ 原样继承。Exec_v6 = Exec_v5 ∩ {kc_prov=1}，故嵌套严格成立（kc_prov 非恒真）。

**形式化目标（增量）**：
1. EFM 提议器 π_EFM(·|c) = (B 冻结, A_i 站点 LoRA, S_i 技能包络)；训练只更新 A_i；supp(π_EFM) 受 n_flow 与 S_i 约束。
2. 可移植证书 Cert = (H_gate, H_weights, H_ctx, H_traj, verdict, margin, nonce, sig_site)；cid = H(Cert)；Merkle 追加日志 + 包含证明 π_incl + 一致性证明 π_cons。
3. 反例审计 OCA：提交 e → 参考门复算 → dispute cert；有效则原证书失效 + 回滚；审计覆盖度 κ_audit 进入定理 11 的界。
4. 供应链证明 manifest = (sbom_root, gate_hash, weights_hash, build_hash, license)；kc_prov = 1[attest(manifest, running_image) ∧ verify_sig(release)]。
5. 定理 9（可复算证书的确定性与等价类可靠性）、定理 10（透明日志 equivocation 检测）、定理 11（外部真值对固化博弈的覆盖度收缩）、定理 12（供应链绑定与 fail-closed 组合）、定理 13（八门嵌套）。
6. Exec_CADVS-v6 = {x ∈ supp(π_EFM) : ∧_{i=1..7} kc_i(x,c;τ_i^5)=1 ∧ kc_prov(running_image)=1} ⊆ Exec_CADVS-v5。

**本轮最大风险**：**可验证性剧场（verification theater）**——开源 + 透明日志只保证「这份代码确实产出了这份证书」，不保证门规范正确、威胁模型完整、审计覆盖充分；「多眼」是经验覆盖而非定理，恶意分叉/依赖投毒/选择性披露可在同一证书格式下绕过，反而制造「已被外部审计」的安全幻觉，挤出更难的内部对抗工作。

### IP-498 PCT：可移植证书透明日志（签发/验证 O(log n)，审计异步）

```python
@dataclass
class PortableCertificateTransparency:
    """PCT：内容寻址执行证书 + 只增 Merkle 日志（类比 RFC 6962）。
    只证明「工件产出了证书」，不证明「门规范正确」（诚实边界，见定理 9）"""
    log: MerkleAppendOnlyLog
    gossip: GossipProtocol

    def issue(self, fields: dict, site_key) -> Certificate:
        body = canonical_json(fields)             # 含 H_gate,H_weights,H_ctx,H_traj,verdict,margin,nonce
        cid = blake3(body)                        # 内容寻址
        sig = sign(site_key, cid)
        leaf = blake3(b"\x00" + body + sig)       # 域分离
        idx = self.log.append(leaf)               # 只增
        incl = self.log.inclusion_proof(idx)      # O(log n)
        self.gossip.broadcast((idx, incl, self.log.root()))
        return Certificate(cid=cid, body=body, sig=sig, idx=idx, incl=incl)

    def verify(self, cert, gate_image, weights) -> bool:
        # 第三方复算：内容地址 + 签名 + 包含证明 + 门/权重哈希一致
        return (blake3(cert.body) == cert.cid
                and verify_sig(cert.site_pk, cert.cid, cert.sig)
                and self.log.verify_inclusion(cert.idx, cert.incl)
                and cert.body.H_gate == hash_image(gate_image)
                and cert.body.H_weights == hash_weights(weights))

    def detect_equivocation(self, a: Proof, b: Proof) -> Dispute | None:
        # 同一 idx 两个不同 root，或同一 (H_gate,H_traj,nonce) 两个不同 verdict
        if a.idx == b.idx and a.root != b.root:
            return Dispute.equivocation(a, b)
        if a.key == b.key and a.verdict != b.verdict:
            return Dispute.equivocation(a, b)
        return None
    # 隐私：H_ctx 用带密钥的加盐哈希；仅承诺，不发布明文上下文（见 R64）
```

### IP-499 OCA：开源反例审计（提交/复算异步；失效与回滚）

```python
@dataclass
class OpenCounterexampleAudit:
    """OCA：开源反例赏金 → 参考门复算 → dispute cert → 失效/回滚。
    这是 v5-R57 自指回路的外部真值注入通道（定理 11）"""
    ref_gate: ReferenceGate          # 审计发布的可复现参考门镜像
    bounty: BountyLedger
    dispute_log: MerkleAppendOnlyLog

    def submit(self, e: Episode, claimed: Certificate) -> Dispute:
        replay = self.ref_gate.evaluate(e.x, e.c)     # 独立复算
        if replay.verdict == REJECT and claimed.body.verdict == ACCEPT:
            d = Dispute(claimed.cid, e, replay.proof)
            self.dispute_log.append(blake3(canonical_json(d)))
            self.bounty.pay(e.author, severity(replay))
            self.invalidate(claimed.cid)              # 级联失效依赖该证书的固化片段
            return d
        return Dispute.invalid()

    def audit_coverage(self, window) -> float:
        # κ_audit = 被独立复算证书数 / 总签发数（进入定理 11 的界）
        return self._recomputed(window) / max(1, self._issued(window))
```

### IP-501 EFA-v6：八门（七门 + kc_prov）+ PCT 签发

```python
@dataclass
class EvidenceForgingAssemblerV6:
    """EFA-v6：kc_prov 先于一切提议；其余七门复用 v5 级联"""
    efma: EmbodiedFoundationModelAdapter
    pct: PortableCertificateTransparency
    oca: OpenCounterexampleAudit
    scak: SupplyChainAttestationKernel
    v5: EvidenceForgingAssemblerV5

    def select(self, x0, t_now, rule_id, context):
        # 第 0 层：来源门（唯一新增硬门），先于提议 → 不可信工件不可能提议
        if not self.scak.kc_prov(context.image, nonce=t_now):
            return False, None, 'PROVENANCE_REJECT'      # fail-closed
        ok, best, why = self.v5.select(x0, t_now, rule_id, context)
        if not ok:
            return ok, best, why
        # 通过者签发可移植证书（H_ctx 加盐；不发布明文上下文）
        cert = self.pct.issue({
            'H_gate': hash_image(context.image),
            'H_weights': hash_weights(self.efma),
            'H_ctx': salted_hash(context),
            'H_traj': hash_traj(best),
            'verdict': ACCEPT, 'margin': certified_margin(best),
            'nonce': nonce(t_now)}, context.site_key)
        return True, best, f'FORGED_OAEF:{cert.cid[:12]}'

    def ecs_v6(self, base, e_out, prov_ok) -> float:
        eta_efm = sigmoid(self.lam_env * (1.0 - e_out) - self.b_efm)
        eta_prov = 1.0 if prov_ok else 0.0
        return base * eta_efm * eta_prov
```

### 集成流水线（v5 → v6）

```
离线/供应链（小时~天级）：
  源码 ──▶ 可复现构建（Nix/Repro）──▶ gate_hash / build_hash ──▶ SBOM(syft)
       ──▶ 多签发布（sigstore/cosign，k-of-m 根）──▶ 发布清单 manifest
  VLA 基座 B 冻结 + 站点 LoRA A_i ──▶ 权重哈希 ──▶ 并入 manifest
  独立重建校验 + 远程证明模板 + 许可证审计（copyleft 衍生门必须开源）

在线准入（异步，秒级）：
  kc_prov（先于提议）──▶ 失败即 PROVENANCE_REJECT（fail-closed）
  EFMA.propose (K=8) ──▶ 包络/新颖度软约束 ──▶ v5 七门级联（VACK/BCK）
       ├─ 全灭 ──▶ fail-closed 回退 v5 规则提议
       └─ 通过 ──▶ PCT.issue（内容寻址 + 签名 + Merkle 追加 + gossip）

审计（外部/异步，持续）：
  第三方 PCT.verify 复算 ──▶ 发现 equivocation/失效 → Dispute
  社区 OCA.submit 反例 ──▶ RefGate 复算 ──▶ dispute cert ──▶ 失效+回滚+赏金
  κ_audit / ρ_audit ──▶ 定理 11 的覆盖度界 ──▶ 决定固化信任权重

在线控制环（目标 < 0.6 ms，继承 v5）：
  每周期：EEK + BCK（事件触发 + 缓存证书）；kc_prov 结果按会话缓存 O(1)
  证书消费：τ^5 预计算；PCT/OCA/SCAK 全部在控制环之外
```

## 3. 复杂度分析（增量更新）

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 | 实时性指标 |
|---|---|---|---|---|
| EFMA.propose | O(K·(L·d_model + d_act)) | O(L·d_model) | K=8, L=64, d=256 | ~10–40 ms GPU，仅准入/10 Hz 预览 |
| EFMA.train_adapter | O(n_epi·L·d_model) DP-SGD | O(θ_A)（LoRA 很小） | 低秩 r=16 | 离线，分钟~小时 |
| PCT.issue | O(log n) 追加 + O(1) 哈希/签名 | O(n) 日志 | n 证书数 | ~1–3 ms，准入后异步 |
| PCT.verify | O(log n) 包含证明 | O(log n) | — | ~1–5 ms，外部审计 |
| PCT.detect_equivocation | O(1) 比对 | O(1) | — | 收到 gossip 即检 |
| OCA.submit | O(cost(RefGate 复算)) | O(1) | — | 异步，秒~分 |
| SCAK.kc_prov | O(verify_sig + attest) | O(1) 缓存 | 每会话一次 | ~2–10 ms 启动/会话，控制环 O(1) 查缓存 |
| EFA-v6 在线增量 | 继承 v5 ~0.6 ms + kc_prov 缓存查 + PCT 异步 | — | — | 控制环 P99 仍 ~0.55 ms |

**通信开销**：PCT 每条证书叶 ~1–2 KB（含签名的承诺）；gossip 每站点每轮 O(log n) 证明；OCA dispute ~几 KB + 反例片段引用（内容寻址）；SBOM/manifest ~几十 KB，签名下发、版本化。原始人脸/上下文永不上日志（仅加盐承诺）。

**实时性说明**：v6 的所有新机制（EFM 基座推理、PCT 签发、OCA 复算、SCAK 证明）都在准入/离线/外部审计时域，**不进入 1 kHz 控制环**；控制环只消费 v5 已有的预计算阈值与缓存证书，kc_prov 结果按会话缓存，故 P99 不退化。

## 4. 正确性论证（增量更新）

### 引理 45（证书内容绑定的抗伪造性）

**陈述**：设哈希 H 抗碰撞、签名不可伪造。若 Cert' 与已签发 Cert 的 cid 相同但 body 不同，或 sig 不能由 site_pk 验证，则伪造成功的概率 ≤ negl(λ)。故 cid 唯一绑定 `(H_gate,H_weights,H_ctx,H_traj,verdict,margin,nonce)`。∎

### 引理 46（复算确定性与 ε_rep 等价类）

**陈述**：门评估在浮点/并行归约下非确定，但存在 ε_rep 使同一 `(x,c,image,weights)` 的两次诚实复算满足 `|margin_1 − margin_2| ≤ ε_rep` 且 verdict 在远离阈值处一致。定义证书等价类 `[Cert]_ε`：margin 差 ≤ ε_rep 且 verdict 相同。则诚实复算落在同一等价类；伪造需跨出等价类（引理 45）。∎

**诚实边界**：靠近阈值 `|margin−τ| ≤ ε_rep` 的证书处于「争议带」，复算可能翻转 verdict；工程上必须把争议带证书标记为「待人工/多副本复算」，不能当作确定证据。

### 引理 47（Merkle 包含/一致性可靠性）

**陈述**：标准 Merkle 树，包含证明 π_incl 使验证者以 O(log n) 确认 leaf 属于 root_t；一致性证明 π_cons 确认 root_t 是 root_{t'} 的只增扩展。在 H 抗碰撞下，伪造包含/一致性证明的概率 ≤ negl(λ)。∎

### 定理 9（可移植证书可靠性 / 第三方复算）

**陈述**：诚实验证者 V 对证书 Cert 执行 `PCT.verify`，若接受，则在引理 45/46/47 与「RefGate 复现构建哈希一致」下，Cert 声明的 `(H_gate,H_weights,H_traj,verdict)` 与审计发布的门/权重在 ε_rep 等价类内一致；任何诚实复算者得到同一等价类。伪造/篡改证书被拒的概率 ≥ 1−negl(λ)。∎

**证明**：内容寻址（引理 45）+ 签名不可伪造 + 包含证明（引理 47）+ 复算确定性（引理 46）逐项成立，任一不满足即 verify 返回 False。∎

**诚实边界**：定理 9 只保证「证书忠实记录了某次门评估」，**不保证门规范本身正确**（规范错 → 证书仍可忠实记录错误判定）。这是「可验证性 ≠ 安全性」的形式化分界。

### 定理 10（透明日志的 equivocation 检测）

**陈述**：设日志只增且 gossip 图在时间 T 内连通。若站点 S 对审计者 A、B 出示两条互相冲突的视图（同一 idx 不同 root，或同一 (H_gate,H_traj,nonce) 不同 verdict），则 A 或 B 在收到对方 gossip 后能构造并验证一个 Dispute，概率 ≥ 1−negl(λ)（H 抗碰撞）。∎

**证明**：冲突视图对应两个不同的 Merkle 路径；一致性证明（引理 47）无法同时成立，任一持有双方证明的审计者立即检测。gossip 连通保证证明最终相遇。∎

**诚实边界**：网络分区/故意扣留（withholding）可**延迟**检测，但不能在最终连通后**永久**隐藏；不提供实时性保证。

### 定理 11（外部真值对固化博弈的覆盖度收缩）

**陈述**：设 G_t 为第 t 轮「通过门但违反规范」的博弈证书集合。若 OCA 以覆盖度 κ_audit、单证条件击中率 ρ_audit 独立审计，且 dispute 有效即失效并回滚，则存活博弈质量的期望满足 `E[|G_{t+1}|] ≤ (1 − κ_audit·ρ_audit)·E[|G_t|] + δ_new`，其中 δ_new 为新引入的博弈质量。故存活博弈随审计轮次几何衰减，衰减率随 κ_audit·ρ_audit 单调增。∎

**证明**：每轮独立审计，未被击中的博弈以因子 (1−κ_audit·ρ_audit) 留存；被击中者失效回滚；新博弈由新提议引入 δ_new。取期望即得。∎

**诚实边界**：这是**覆盖度条件界**，不是根除保证——κ_audit 与 ρ_audit 真实值未知，若审计覆盖趋零（「多眼」实为「无眼」），退化为 v5-R57 的无界自指；Linus 定律不是定理，此式恰好暴露它依赖的经验参数。

### 定理 12（供应链绑定与 fail-closed 组合）

**陈述**：若远程证明不可伪造、根密钥未泄露、可复现构建成立，则 `kc_prov(image)=1` ⇒ 运行镜像的 `(gate_hash,weights_hash,build_hash,deps)` 与审计发布的 manifest 一致；`kc_prov=0` ⇒ EFA-v6 直接拒绝（PROVENANCE_REJECT）。因此 Exec_v6 只含「在审计门/审计权重上产生」的执行。∎

**证明**：kc_prov 是各等式的合取；证明系统可靠性与签名不可伪造性给出匹配；fail-closed 由 EFA-v6 第 0 层短路保证。∎

**诚实边界**：根密钥泄露、TEE 侧信道、构建不可复现会破坏前提；供应链攻击面被**收窄到信任根**，而非消除。

### 定理 13（八门执行集嵌套）

**陈述**：`Exec_CADVS-v6 = Exec_CADVS-v5 ∩ {x : kc_prov(image)=1} ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29`。存在至少一个未证明部署使 kc_prov=0，故包含严格。∎

**证明**：向谓词加合取只缩小集合；v5 七门与阈值 τ^5 原样继承（定理 6/8）；kc_prov 非恒真。∎

### 定理 v6（开源可审计基座下的执行集收缩，总装）

**陈述**：在 v5 假设 (B1)~(B7) 及新增 (B8) 远程证明/根密钥可信、(B9) 复算在 ε_rep 等价类内确定、(B10) OCA 参考门镜像与发布哈希一致下：
(i) Exec_CADVS-v6 ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29（定理 13）；
(ii) 可移植证书可被第三方复算且忠实（定理 9）；
(iii) 透明日志可检测 equivocation（定理 10，最终连通）；
(iv) 外部反例审计使博弈质量按 κ_audit·ρ_audit 几何收缩（定理 11，条件界）；
(v) 供应链绑定使执行只发生在审计门/权重上，否则 fail-closed（定理 12）；
(vi) 七锚完备性（v5 定理 8）保持，kc_prov 为第 8 硬门（新增威胁类，非新锚）。

**证明**：(i) 定理 13；(ii)(iii)(iv)(v) 分别由定理 9/10/11/12；(vi) 锚集合不变 + 新增门只紧。∎

**诚实声明**：(i) 定理 11 是覆盖度条件界，审计覆盖未知时不构成安全保证；(ii) 定理 9 不含「门规范正确性」，开源可验证的是实现与记录，不是需求与威胁模型的正确性；(iii) 信任根（多签密钥、TEE）是单点，供应链攻击被收窄而非消除；(iv) 透明日志与 v5 人脸隐私（R56）存在结构性张力，靠加盐承诺与粗粒度缓解，非彻底解决；(v) 恶意分叉可复制证书格式，用户/部署方必须靠 manifest 与根签名区分，无法从格式上阻止。

## 5. 实验设计与初步结果（仿真 + 本地供应链；真实机队/跨站列入第 7 轮）

### 5.1 实验设计

- **平台**：开源 VLA（OpenVLA/π0 类）冻结基座 + LoRA 适配器；MuJoCo 3.x + MJX；本地 git 式 Merkle 日志与模拟审计者；供应链用 Nix 可复现构建 + syft(SBOM) + cosign(签名) + 模拟 TPM 证明。
- **对照**：v5-full、v6-full、消融 B1（去 kc_prov——供应链攻击）、B2（去 PCT——私有日志、equivocation 不可见）、B3（去 OCA——自指固化漂移持续）、B4（闭源门——无外部复现）、B5（EFM 去技能包络——涌现能力失败）。

- **指标**：跨具身成功率；后门触发成功率；equivocation 检测率/延迟；门博弈通过率随轮次曲线；复算不一致率；κ_audit/ρ_audit；kc_prov 开销；构建可复现率；元数据隐私推断 AUC。

## 7. 本轮最大风险（最终确认）

**一句话**：**可验证性剧场**——开源 + 透明日志只保证「这份代码确实产出了这份证书」，不保证门规范正确、威胁模型完整、审计覆盖充分；「多眼」是经验覆盖而非定理，恶意分叉/依赖投毒/选择性披露可在同一证书格式下绕过，反而制造「已被外部审计」的安全幻觉，挤出更难的内部对抗工作。
