# 第 10 轮（新灵感循环第 1 轮；本轮灵感：「商业模式」×「轻量化设计」）
> **基线**：第 9 轮 MetricVoiceGauge-ACMD（定义 532–539；引理 82–86；实验 E551–E570）。
> 本轮纪律：**经济层只定价、不降安全；轻量层只少算、不删证书**。两个灵感治理 v9 的两笔债：价值债（系统能算 WCET 与证书，却算不出“哪个能力值多少钱、承诺的 SLA 是否兑现”）与体积债（14 个模块在所有部署上全额运行，缺少“同一内核、多个经认证的轻量产品”路径）。所有新组件都是可选增强：失效即退回单一全能力 SKU，严格等价 v9。

## 0. 直觉与动机

**灵感 1（商业模式 → 把“能力”变成可计价、可验证、可退化的服务）**
直觉：v9 已经有一套精密的“成本会计”——WCET、截止期、块证书、中立元注入日志——却没有任何“价值会计”。一台以 RaaS（Robot-as-a-Service）交付的家用机器人，收费按成功任务、在线率与 SLA 结算；客户、保险方与审计方真正想看的，恰好是 v9 已经产生但未被利用的安全/退化事件。当前系统无法回答“哪个能力档位真正挣得它的价格”与“我们是否兑现了承诺”，只能靠人工日志。核心创新：**可验证服务层（Verifiable Service Layer, VSL）**——任务准入与资费 + 防篡改服务证据链，把 v9 的契约表和块证书升级为计费与 SLA 结算的原始凭证。关键商业设计：**按能力档位定价、按认证结果付费；安全永不进入价目表**（P13 安全不可交易律）。

**灵感 2（轻量化设计 → 经认证的能力阶梯，而非删功能）**
直觉：通常的轻量化是“更小的模型/更便宜的传感器”，但在安全关键机器人上，朴素压缩会直接让证书失效。反过来，把轻量化做成**认证产品线**：每个模块有一条档位阶梯（全量 → 蒸馏 → 量化 → 早退），每级附一个可验证误差包络 η；只有当当前安全余量 ρ ≥ 该级的有效误差 L·η 时才允许降档。一个内核通过契约表数据实例编译出多个 SKU，每个 SKU 仍是 v9 退化格中的一个点。核心创新：**认证轻量替身（Certified Lite Surrogate, CLS）**与**能力档位格（Capability Lattice）**。关键纪律：**轻量不是删除，而是“可证明地少算”**；余量一缩，立即升档，绝不反向。

**两灵感交汇 = 认证 SKU 市场（Certified SKU Market, CSM）**
商业模式问“什么能力能以什么价格卖”，轻量化设计答“什么能力能在多大算力/物料上安全跑”，v9 答“任何东西坏了如何严格退化”。三者合流：一个 SKU =（硬件档，能力档位向量，SLA 等级，资费）；价格沿能力格单调上升，安全沿能力格保持不变。经济层只能在**已认证等价物之间选择或拒绝任务**，永不放松 M₀/SpatialCert/FaultCert/AC 守卫。服务证据链让“账单”与“安全审计”成为同一份工件：**为证据付费，而不是为承诺付费**。

## 1. 研究问题（轮次升级版）

- **Q1（安全-经济分离）**：在什么不变量下，可证明任意资费、任意 SLA 罚则、任意准入策略都不改变 v9 的安全保证？“价格可影响选择集，但不可扩张安全动作集”如何形式化并机器检查？
- **Q2（认证轻量化组合）**：多个模块同时降档时，误差包络如何组合？逐模块 η 的加性/最坏组合是否足够，还是需要沿计算链的 Lipschitz 传播？档位切换的瞬态如何不破坏证书？
- **Q3（证据与激励相容）**：由被计费系统自己生成的证据链，如何抵抗“漏报失败、把故障归因客户”的激励性篡改？客户侧挑战-应答与第三方锚定能否把“自证”变成“互证”？

## 2. 设计原则（在 P10–P12 基础上新增 P13–P16）

**P13 安全不可交易律（Safety Non-Tradability）**
资费、SLA 等级、准入价值只影响“做不做、用哪一级认证等价物做”，绝不影响硬安全判定的输入与阈值。形式化：安全动作集 A_safe(s) 与价格变量 p 无关；经济层的可选集 ⊆ {A_safe(s) ∪ 拒绝}。

**P14 单一内核多档产品律（Certified Product Line）**
每个 SKU 的行为都是 v9 契约表的一个数据实例，位于 v9 退化格内；不为低价 SKU 维护分叉的安全代码。SKU 的差异只允许来自契约表、档位向量与硬件约束。

**P15 证据即账单律（Evidence-as-Invoice）**
可计费事件必须能映射到服务证据链（SEL）中的一条可验证记录；无证据不计费（计费中立元 b^⊥=0）。SEL 在 v9 的块边界（5Hz）批量锚定，摊销开销 O(1)/块；本地运行不因账本故障而停止。

**P16 按需轻量化律（Just-Enough Capability）**
模块 m 的档位 r 仅在 L_m·η_{m,r} ≤ ρ(s) 且满足当前 SLA 新鲜度时可用；否则升档。升档总是允许的，降档必须重新取证。安全余量单调决定能力档位，而非价格。

## 3. 与基线的接口（如何退化）

- CSC（SKU 编译器）失效 ⇒ 使用单一全能力 SKU，契约表 = v9 原表；
- SCB（服务经纪/准入）失效 ⇒ 接受所有实时可行的任务、价格记 0，等价 v9 行为；
- SEL（证据链）失效 ⇒ 进入“运行但不索赔”模式（b^⊥=0），本地闭环等价 v9；
- CLS（轻量替身）失效/超包络 ⇒ 全模块升到全量档，等价 v9；
- EDG（经济退化门）失效 ⇒ 固定最高安全档位，禁止任何降档，等价 v9；
- v9 的 AC/MW/ID/DA/SPR/Cal 失效 ⇒ 按 v9 五级链继续退化到 v8/v7/v6；
- 商业约束冲突（客户要求超 SLA 或要求降安全）⇒ **拒绝任务**，而不是降安全。

## 4. 预期贡献

1. **认证 SKU 产品线**：把轻量化从“压缩模型”变为“在能力格上编译经认证的退化点”，一个内核覆盖多硬件/多价位；
2. **可验证服务层**：任务准入、资费与 SLA 结算直接建立在 v9 证书和中立元日志上，安全审计与计费共用证据；
3. **安全-经济正交定理**：证明价格/罚则/准入不扩张安全动作集，为“可售安全关键机器人”提供可审计边界；
4. **认证轻量替身与误差代数**：给出逐模块与组合误差包络、升/降档瞬态安全条件；
5. **实验 E571–E590**：SKU 等价、替身误差标定、SLA 证据、抗博弈、成本-安全 Pareto、多硬件档与端到端任务。

## 5. 本轮最大风险

**一句话**：证据链由被计费的系统自己生成，而商业模型又把“在线率/成功率”变成收入函数——若缺乏客户侧挑战-应答与外部锚定，系统就有激励把失败记成“客户取消”、把降档记成“正常档位”，于是经济优化会悄悄污染安全审计所依赖的同一份数据，形成“账面安全、实际风险”的 Goodhart 失效。

# 第 10 轮产物 · 创新点清单 v10：**MetricVoiceGauge-SLIM**（Service-Level & Lightweight Incentive Middleware）

> 背景：第 9 轮 MetricVoiceGauge-ACMD（定义 532–539；引理 82–86；实验 E551–E570）。
> 本轮灵感：「商业模式」×「轻量化设计」
> **继承纪律**：MetricVoiceGauge 九不变式与 v9 的 AC/MW/ID/DA-SPR-Cal 全部保留，语义不变。v10 只新增**产品线编译、服务准入/计费、轻量替身**三件事；它们都不进入硬安全判定的输入，只决定“用哪一级已认证等价物执行、是否接单、如何出账”。任一新增环节失效 ⇒ 退回单一全能力 SKU，严格等价 v9（引理 93），而非行为漂移。

## 1. 符号体系增量（定义 540–548）

**新增定义 540（能力档位格 CapabilityLattice）** 每个模块 m 有档位集 R_m，按资源占用与精度从轻到重全序：`full ≻ quant ≻ distill ≻ early_exit`。能力向量 c∈C=∏_m R_m，定义 c ⪯ c′ ⇔ ∀m, rank(c_m) ≤ rank(c′_m)；格运算为逐分量 max/min。价格函数 p:C→R_{≥0} 沿 ⪯ 单调不减；安全不变式集合 S 对所有 c 相同，**不允许价格改变 S**。

**新增定义 541（认证 SKU CertifiedSKU）** sku=(h,c,σ,p) 合法当且仅当：
```
(1) Σ_m Ŵ_m(c_m,h) ≤ B_dec(h) 且 E_energy(c,h) ≤ P_max(h)；
(2) Φ(c,h) 通过 v9 契约可行性检查（EDF、截止期、中立元路径可达）；
(3) Φ(c,h) 在 v9 退化格内（引理 93 的模拟关系）；
(4) p 与 c 满足价格单调性，且 p 不进入任何安全谓词。
```
SKU 是**部署单元**：同一二进制内核 + 不同契约表数据 + 不同档位权重。

**新增定义 542（轻量替身证书 CertifiedSurrogate）** 对模块 m、档位 r，全量映射 f_m 与替身 f_{m,r} 的认证误差为
```
η_{m,r} = sup_{x∈D_trust} ‖f_{m,r}(x) − f_m(x)‖∞
```
用 split-conformal 在标定集上取有限样本上界（覆盖率 1−α），再乘安全系数 1.2。有效误差 ε_{m,r}=L_m·η_{m,r}。档位 r 在状态 s 可用 ⇔ `ε_{m,r} ≤ ρ(s)` 且 `risk_SLAM < τ_SLAM` 且 `Δ_dom < τ_dom`。

**新增定义 543（安全余量 SafetySlack）** 由 v9 块证书的活跃约束归一化取最小：
```
ρ(s) = min{ (g(s) − d_safe) / g_scale,
            (τ_eff − e(s)) / τ_scale,
            (γ_grasp_margin) / γ_scale,
            (Δ_dom 与 risk_SLAM 的信任域余量) }
```
ρ(s) ≥ 0 是 v9 证书有效的前提；ρ 越小，可用档位越重。ρ 由本地原始数据计算，**不读价格**。

**新增定义 544（服务证据链 ServiceEvidenceLedger）** 事件
```
e_t = (t, sku_id, task_id, level, digest(Ĉ_t), injections, outcome,
       billable, nonce_j, h_{t−1})
h_t = H(e_t ‖ h_{t−1})
```
每 K_block=10 个控制周期（与 v9 的 5Hz 块边界对齐）把区间内事件构造成 Merkle 树，根 R_j 写入本地锚点并可由客户/第三方共签。验证单条事件只需 O(log n) 的包含证明；验证整段只需比对 R_j 与链头。事件 `billable` 为真必须同时具备：任务已准入、证书未失效、无未解释的中立元注入。

**新增定义 545（任务准入 TaskAdmission）** 任务 τ=(v,d,c_req)。准入当且仅当
```
c_req ⪯ c_current,
U(t) + ΔU(τ) ≤ 1 − u_res,
v(τ) ≥ c_exec(τ) + λ_r·E[risk(τ)] + c_credit(τ),
```
其中 U 为 EDF 利用率，u_res 为预留余量，c_exec 为算力/能耗成本，c_credit 为 SLA 信用期望。排序按 `(v/d)·a(t)`，a(t)=1+β_age·wait(t) 防止低价值长任务饿死。

**新增定义 546（SLA 与信用 ServiceLevelAgreement）** σ=(A_target, L_target, S_target, γ)，分别对应在线率、p99 时延、任务成功率与信用系数。窗口内由 SEL 计算 (A,L,S)，信用
```
credit = γ · price · [α_A·max(0,A_target−A) + α_L·max(0,L−L_target)/L_target
                     + α_S·max(0,S_target−S)]
```
且 `credit ≤ price`、`无有效证据 ⇒ credit=0 且 billable=false`（计费中立元）。

**新增定义 547（轻量档位选择 RungSelection）** 给定状态 s 与 SKU，选择
```
c*(s) = argmax_{c∈C_feasible(s)} [ E[reward | c] − J_cost(c) − E[credit(c)] ]
C_feasible(s) = { c : ∀m, L_m η_{m,c_m} ≤ ρ(s)；Φ(c) EDF 可行；
                 预测 SLA 满足；c_req(当前任务) ⪯ c }
```
安全可行性是硬约束；经济项只在可行集内排序。由单调性（引理 96）知这是关于 ρ 的阈值策略。

**新增定义 548（计费中立元 BillingNeutralElement）** b^⊥=0 满足 b ⊕ b^⊥=b。SEL 不可用、证据缺失、争议未决时一律取 b^⊥：**无证据不计费**；同时本地闭环不进入任何退化级，继续以 v9 行为运行。

## 2. 形式化定义（要点与升级）

**定义 493/521/531（v9 继承）** 六层指标、DA-OTL 与软硬约束衔接不变；块证书、中止点集、中立元注入、EDF 契约表原样保留。

class CertifiedLiteSurrogate:
    def __init__(self, full_models, surrogates, eta, lipschitz):
        self.full, self.lite = full_models, surrogates
        self.eta, self.L = eta, lipschitz

    def allowed(self, m, r, s):
        if r == "full":
            return True
        if s.delta_dom >= s.tau_dom or s.risk_slam >= s.tau_slam:
            return False
        return self.L[m] * self.eta[(m, r)] <= safety_slack(s)   # 定义 542/543

    def forward(self, m, r, x):
        return self.full[m](x) if r == "full" else self.lite[(m, r)](x)


# IP-361 EconomicDegradationGate：经济退化门（安全硬门，价格只读）
class EconomicDegradationGate:
    def __init__(self, cls, sku):
        self.cls, self.sku = cls, sku
        self.locked = False

    def select(self, s, task_req=None):
        if self.locked:                                        # EDG 失效 → 锁最高档
            return self.sku.heaviest_vector()
        feasible = []
        for c in self.sku.lattice:
            if task_req is not None and not leq(task_req, c):
                continue
            if all(self.cls.allowed(m, c[m], s) for m in range(len(c))):
                feasible.append(c)
        return max(feasible, key=lambda c: self.sku.score(c, s)) # 只在安全可行集内排序


# IP-358 ServiceContractBroker：准入、定价、SLA
class ServiceContractBroker:
    def __init__(self, sku, ledger, u_res=0.1, beta_age=0.01):
        self.sku, self.ledger = sku, ledger
        self.u_res, self.beta_age = u_res, beta_age

    def admit(self, task, edf_util):
        if not leq(task.c_req, self.sku.c_current):
            return False
        if edf_util + task.delta_u > 1.0 - self.u_res:         # 定义 545
            return False
        value = task.v
        cost = self.sku.exec_cost(task) + task.lam * task.risk
        return value >= cost + self.sku.expected_credit(task)

    def priority(self, task, now):
        wait = now - task.arrival
        return (task.v / max(task.d, 1e-6)) * (1 + self.beta_age * wait)


# IP-359 ServiceEvidenceLedger：服务证据链
class ServiceEvidenceLedger:
    def __init__(self, K_block=10, hash_fn=sha256):
        self.K, self.H = K_block, hash_fn
        self.head = b"\x00" * 32
        self.buf, self.anchors = [], []

    def append(self, event):
        event = dict(event, h_prev=self.head)
        event["h"] = self.H(canonical(event))
        self.head = event["h"]
        self.buf.append(event)

    def anchor(self, client_nonce):
        root = merkle_root([e["h"] for e in self.buf])
        self.anchors.append((root, client_nonce, self.head))
        self.buf.clear()
        return root

    def prove(self, idx):
        return merkle_proof(self.anchors, idx)

    def billable(self, event):
        return (event["billable"] and not event["injections"]
                and event["cert_valid"] and self.verify(event))


# 主闭环集成：MetricVoiceGauge-SLIM
def metricvoicegauge_round_10(M, s, obs, task, audio_stream=None, ...):
    # ---- v9 感知侧契约（价格不进入此路径）----
    ctx = mw_default_ctx()
    results = middleware.run_cycle(v9_perception_runners(M, obs), ctx)
    ctx.delta_dom, ctx.risk_slam = results["DA_ML"], results["SPR"]

    # ---- 经济层：准入 → 选档 → 记证据（全部为安全非必需）----
    if broker.admit(task, edf_util=M.edf_util):
        c = edg.select(s, task.c_req)                          # 只在认证可行集内
        sku_runtime = csc.compile(c, task.sla, task.price)
    else:
        ledger.append({"type": "reject", "task": task.id, "billable": False})
        return M.inherited_v9_path(ctx)                        # 等价 v9 空转

    # ---- v9 决策闭环（原样，只把轻量替身作为可选实现注入）----
    current_chunk = chunker.generate_chunk(
        ctx.state, ctx.delta_dom, ctx.tau_dom,
        trust_ok=(ctx.delta_dom < ctx.tau_dom and ctx.risk_slam < M.tau_slam),
        surrogate=cls)
    verdict, k_next = chunker.midchunk_guard(current_chunk, k_exec, live_obs)
    if verdict == "abort":
        current_chunk.execute_safe_stop_at(k_next); current_chunk = None
    else:
        execute(current_chunk.actions[k_next])

    C, spatial_cert, claims, metrics, rewards = M.inherited_v8_path(ctx)
    ledger.append({"type": "cycle", "sku": sku_runtime.id, "cert": current_chunk.cert_digest,
                   "level": current_chunk.level, "billable": current_chunk.completed})
    distiller.step(cycle_idx, ctx)

    # ---- 块边界锚定：5Hz，O(1) 摊销 ----
    if cycle_idx % ledger.K == 0:

## 4. 推导

**引理 93（产品线安全传递 / SKU ⊆ v9 退化格）** 若 Φ(c,h) 满足定义 541 且所有降档通过定义 542 的包络检查，则 sku 的每条执行轨迹都与 v9 在对应退化级上的轨迹在安全可观测变量上等价。证明：契约表只替换数据、`safety_fingerprint` 相同；轻量替身只在 `Lη ≤ ρ` 时替换模块输出，由引理 94 该替换不改变证书符号；经济层只在认证可行集内选择或拒绝，拒绝时执行 v9 空转路径。对每个决策点做模拟关系归纳即得。∎

**引理 94（轻量替身误差传导）** 设模块 m 的输出误差 ≤ η_{m,r}，下游证书映射 f_cert 对 m 的 Lipschitz 常数为 L_m。则在固定其他模块输出时，
```
|f_cert(f_{m,r}(x)) − f_cert(f_m(x))| ≤ L_m η_{m,r}
```
若多模块同时降档且证书映射的联合 Lipschitz 常数为 L_Σ=∏_m L_m（串行链），则总误差 ≤ Σ_m L_Σ η_{m,r}；要求 `L_Σ·Ση ≤ ρ(s)` 即可保证证书符号不翻转。升/降档瞬态采用 v9 的零阶保持：新档位未完成一个块周期的证书复核前，继续执行旧档位最后认证的输出；切换时间 ≤ 1 个块周期（≤200ms）。∎

**引理 95（安全-价格正交）** 设价格变量 p 不进入 M₀、SpatialCert、FaultCert、AC 守卫与停车不变式的任何输入。则对任意 p,p′ 与任意状态 s，`A_safe(s;p)=A_safe(s;p′)`；经济层只做 `select ⊆ A_safe ∪ {reject}`。故任何资费/罚则/准入策略都不能使系统选择不安全动作。证明：直接由定义 543/545/547 的变量依赖图得出，p 只出现在目标函数与准入不等式右侧。∎

**引理 96（轻量档位的阈值结构与单调性）** 若 η_{m,r} 随档位变重单调不增、成本单调不减，且 ρ(s) 越大可行档位集越大，则由 Topkis 单调比较静态，最优档位 c*(s) 关于 ρ 单调（ρ 增大 ⇒ 可行集扩张 ⇒ 最优成本不增、精度不降），且存在阈值 ρ_{m,r} 使降档仅在 ρ ≥ ρ_{m,r} 时发生。∎

**引理 97（证据链完备性与抗自证篡改）** 在哈希链抗碰撞假设下：(i) 任意修改单条事件必改变链头，被锚点检出；(ii) 任意遗漏可计费事件会让客户挑战 nonce 对应的应答集合出现缺口，若 nonce 在应答前不可预测，则漏报被检出概率 ≥ 1−2^{−β_chal}；(iii) 无证据时 b^⊥=0，故漏报只会减少收费、不会虚增收费。因此账本故障/缺证是**收益中性偏保守**的失效，但“把失败归因客户”仍可能通过伪造 outcome 发生，需外部共签（见风险）。∎

**引理 98（准入可行性与非饥饿）** 准入规则保持 EDF 利用率 ≤ 1−u_res 并预留安全计算余量，故 v9 的 50Hz 守恒（引理 86）不被破坏；在长期到达率低于剩余容量时，aging 因子 a(t)=1+β_age·wait(t) 保证任意有限价值任务在有限等待后获得准入。过载时系统显式拒绝而不是延迟执行，避免队列爆炸。∎

**引理 99（成本-安全单调折衷）** 若同一任务在能力格上沿 ⪯ 提升档位只会增加成本与安全余量，则 SLIM 的期望成本不高于全能力 SKU，且差值下界为所有可行降档的 `J_cost(full) − J_cost(c*)` 之和；在 ρ 稳定时该差值正比于可降档模块数。实验中以 BOM/算力/能耗三项分别度量。∎

## 8. 本轮最大风险

**一句话**：证据链由被计费的系统自己生成，而商业模型又把“在线率/成功率”变成收入函数——若缺乏客户侧挑战-应答与外部锚定，系统就有激励把失败记成“客户取消”、把降档记成“正常档位”，于是经济优化会悄悄污染安全审计所依赖的同一份数据，形成“账面安全、实际风险”的 Goodhart 失效。
