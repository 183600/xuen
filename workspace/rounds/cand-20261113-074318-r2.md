# 第 2 轮迭代（灵感循环 v3：「多视角视觉」×「虚实迁移」）—— 从“单目 2D 验证器”走向“可观测性门控的 3D 验证器 + 可校准的虚实孪生”

> **本轮不是再加一个模块，而是回头修上一轮的两个隐含假设。** v2 的旗舰 UIP-01′/09′ 默认“看一眼图就能判断进度是否被撤回”，v2 的 UIP-11 默认“Gazebo 计分可以作为真机计分的代理”。两个新灵感词正好各戳破一个：**多视角视觉**说明单目 2D 的“进度”在遮挡、深度退化和相机自身运动下根本不可辨识；**虚实迁移**说明仿真裁判是一台有系统偏差的仪器，不校准就只能“用仿真过拟合仿真”。本轮把 v2 的“扰动恢复闭环”升级为 **几何 grounded 的 3D 验证 + 可校准的数字孪生**，并明确哪些结论只是 D-level 机制证据、哪些必须等真机锚点。

**由此得到两个新的“规则级”约束**：

1. **单目 2D 的进度不是可观测变量，只是它的一个投影。** 当物体沿相机视线运动、被机械臂遮挡、或头部 D435 自身在动时，同一幅 2D 变化可以对应“物体前进”“物体后退”“相机移动”三种完全不同的 3D 事实。用 2D 判 `regressed` 会系统性误报。
2. **虚实迁移不是“把仿真做得更像”，而是“知道仿真在哪个子空间可信 + 校准它的读数”。** 视觉保真度、接触动力学保真度、计分映射保真度是三个不同的迁移问题，不能用一个 domain randomization 打包解决。

## 1. 上轮清单诊断：哪些被两个新词“推翻/升级”

- **UIP-01′/09′（2D 滚动验证 + 撤回检测）→ 升级为 UIP-16。** v2 的 `V(o_t,l,g)` 只吃单帧/单视角外观；本轮改为在 3D 状态 `S_t` 上判进度，并显式区分“物体动了”与“相机动了”。这是**机制级修正**，不是参数调优。
- **UIP-11 GSO（Gazebo 计分神谕）→ 升级为 UIP-17。** 一个未校准的 oracle 只能给“仿真内排名”，不能给“真机排名”。本轮把 GSO 拆成**物理孪生 + 视觉孪生**，并加 UIP-20 的锚点校准。
- **UIP-12 DRF（扰动-恢复数据工厂）→ 并入 UIP-17。** 干扰不再只是“脚本化机械手”，还可以在重建的视觉孪生里做**视角一致**的渲染，生成训练期缺的遮挡/视角变化。
- **UIP-13 ACS（自适应块长）→ 升级为 UIP-18。** 只调 `k` 不够；多视角把“发几张图、多大分辨率、堆几帧”变成同等重要的实时旋钮，必须和 `k` 联合调度。
- **UIP-15 CSG（可信度安全阀）→ 升级为 UIP-19。** 除了延迟/抖动，还要监控“当前观测是否落在仿真/训练分布内”，即 reality-gap monitor。
- **UIP-14 MSGR（模块化技能图）保留**，但技能头改为**视角条件化**：抓取/插入头更多依赖腕部近景，布局/分拣头更多依赖头部双目。
- **UIP-02′（计分步安全网）、UIP-05（语言→可供性）、UIP-08′（N 端口延迟工程）保留**；它们与本轮不冲突，且 UIP-08′ 要吸收多视角带宽预算。

## 2. 两个灵感词：先直觉，再严谨定义

### 2.1 多视角视觉

**直觉解释。** 单目像“闭一只眼看世界”：东西变大可能是它靠近，也可能是相机靠近；东西消失可能是被拿走，也可能是被手臂挡住。多视角不是“多几张图”，而是**用几何把“看起来变了”变成“在某个坐标系里确实变了”**。头部双目负责全局布局和公制深度，腕部近景负责接触细节；两者在同一 3D 坐标系里互相校验。

**严谨定义。** 设第 `v` 个视角的投影为 `π_v(·; ξ_t)`，`ξ_t` 是该时刻相机位姿（由本体感觉 + 离线标定得到），`I_t^v` 是观测。定义场景状态 `S_t = (X_t^1..X_t^K, g_t)`，其中 `X_t^k` 是任务相关物体/关键点的 3D 位姿，`g_t` 是夹爪位姿。多视角状态估计为

```
Ŝ_t = argmin_S  Σ_{v∈U_t} ρ( || π_v(S; ξ_t) - f_v(I_t^v) ||_{Σ_v} )
                 + λ || S - S_{t-1} ||^2
```

`U_t ⊆ {head_L, head_R, wrist_L, wrist_R}` 是**可观测性门控**后的可用视角子集，`f_v` 是轻量关键点/位姿前端（不依赖外部大模型）。任务进度定义为几何谓词

```
P_g(S_t) = 1[ φ_g(S_t) ≥ 0 ]
```

例如 `φ` 可以是“插头插入深度 − 阈值”“碗底与碗口接触”“拉链头位移”“盖子相对瓶口的旋转角”。撤回（regression）定义为

```
R_t = 1[ ∃g: P_g(S_{t-1})=1 ∧ P_g(S_t)=0 ]      （加 2 帧去抖）
```

**可观测性命题（本轮的核心）。** 对一维进度坐标 `q`，单视角灵敏度为

```
s_v(q) = || ∂π_v(S(q); ξ_t) / ∂q || / depth
```

若运动方向与第 `v` 个视角的视线平行，则 `s_v≈0`，该视角对 `q` 的 Fisher 信息退化，**单目无法从该视角辨识 q**；两个视线不平行于运动方向的视角联合，`Σ_v s_v^2 > 0`，`q` 才可辨识。推论：**多视角不是无条件更好；把一个退化视角硬融进来，会把它的噪声变成假撤回。** 必须按 `s_v` 做门控。

**交叉视角一致性。** 定义 `C_t = max_{v∈U_t} ||π_v(Ŝ_t) - f_v(I_t^v)||`。当 `C_t` 大时，3D 估计不可信，此时即使看到“进度下降”也应**先不判撤回**，而是保持上一个可信状态/请求下一帧。这把“撤回检测”从“单帧分类”变成“带置信度的状态估计”。

### 2.2 虚实迁移

**直觉解释。** 仿真不是真机的替身，而是一台**有系统偏差的仪器**：它可能把“插进去 2 mm”读成“插进去了”，把“叠歪了”读成“叠好了”。迁移的任务不是让仪器“看起来像”真机，而是**校准它的读数，并知道什么时候不该信它**。

**严谨定义。** 把迁移拆成三层，避免“一个 domain randomization 包打天下”：

1. **观测迁移（observation transfer）**：`p_real(I|S)` 与 `p_sim(I|S)` 的差异。用视觉孪生（3DGS/NeRF）在多视角重建的真实场景上做新视角渲染，缩小外观/视角差。
2. **动力学迁移（dynamics transfer）**：`p_real(S_{t+1}|S_t,a_t)` 与 `p_sim` 的差异。用真实 state/action 轨迹做系统辨识（质量、摩擦、阻尼、延迟），只把物理孪生用于接触/结构判定。
3. **评测迁移（evaluation transfer）**：仿真计分 `S_sim` 与真机计分 `S_real` 的差异。学一个校准算子 `g`，并给出不确定集 `U`，使

```
| g(S_sim) - S_real | ≤ ε   或   ρ_rank(g(S_sim), S_real) ≥ ρ0
```

以高概率成立。`ρ_rank` 用 Spearman/成对排序风险；这比绝对分数拟合更贴近榜单口径。

**关键：校准不是免费的。** 少量锚点上做全局仿射，可能把噪声当成偏差；分组校准在每组锚点不足时会过拟合。正确做法是**分层收缩 + 门控**：

```
θ_t = θ_group(t) + ε_t,   ε_t ~ N(0, τ²)
```

组效应 `θ_group` 向全局效应收缩；只有当交叉验证的排序风险显著优于“不校准”时才启用校准，并给出 conformal/自助法区间。没有足够锚点时，**保留原始仿真排名并标注不确定度**，而不是硬拟合。

### 2.3 两词交叉：几何是虚实之间的“共同语言”

多视角视觉给虚实迁移提供了一个**共享坐标系**：从真实多视角数据重建场景的 3D 结构（物体位姿、尺寸、相机位姿），在仿真里用同一组位姿渲染/放置资产，于是比较的是**几何谓词**（插入深度、堆叠关系、接触），而不是像素。这样：

- 真机与仿真的差异被分解成“几何结构差”和“外观/动力学差”，前者可标定，后者可控；
- 仿真里的“进度/撤回”与真机里的“进度/撤回”落在同一个 3D 语义上，UIP-16 的验证器可以在两边复用；
- 多视角重建的相机位姿同时充当**虚实对齐锚点**，让“仿真过拟合仿真”的问题变得可检测。

## 3. 瓶颈假设（本轮更新）

- **H1（最高杠杆）**：上一轮 2D 撤回检测的主要误差不是分类器容量，而是**可观测性**。在深度退化/遮挡/头部相机运动下，`regressed` 不可辨识；误报会触发无意义重做，直接烧掉步骤分。
- **H2**：多视角融合存在“负迁移”：把退化视角硬融进来会**比最好的单视角更差**；门控是必要条件，不是锦上添花。
- **H3**：虚实计分差是**任务相关、异方差**的；全局校准在锚点少时会伤排序，必须分层收缩 + 门控 + 最小锚点预算。
- **H4**：测试期没有相机外参，但 `state_d435` + 手臂/腰部本体感觉 + 离线手眼标定可以恢复；**标定误差**会成为 3D 验证器的新主导误差项。
- **H5**：多视角的实时成本是硬约束；最优解不是“永远四路原生分辨率”，而是**任务相关的视角子集 + 分辨率 + 堆叠 + 块长**联合调度。

## 4. 候选与合并 → v3 清单（详见产物区）

围绕两词发散 8 个草案，合并后得到 v3：**新增 UIP-16~20**，其中

- **UIP-16 MV-PVR（旗舰）**：可观测性门控的多视角 3D 进度-撤回验证器，直接替换 UIP-01′/09′ 的 2D 验证器；
- **UIP-17 MV-DT（次旗舰/基础设施）**：物理孪生（Gazebo）+ 视觉孪生（多视角重建）的“双孪生”，承接 UIP-11/12；
- **UIP-20 ARC（方法学）**：锚点校准的排序神谕，给 UIP-17 的仿真分数提供“可信区间/是否可信”的判决；
- **UIP-18 MV-VBS**：视角-块长-分辨率的联合预算调度，升级 UIP-13；
- **UIP-19 RG-Mon**：reality-gap 监控与保守回退，升级 UIP-15。

**本轮押注**：UIP-16 的“观测几何” × UIP-20 的“评测校准”。上一轮押“造出缺失的恢复数据”；本轮押“让判断恢复是否发生的眼睛和尺子都可信”。两者是乘法关系：没有 3D 几何，恢复数据可能教出错误的撤回检测；没有校准，仿真里的“恢复成功”可能只是仪器读数。

## 5. 本轮最大风险

**一句话**：把多视角几何当万能钥匙——在相机外参/手眼标定不准、或唯一可见视角深度退化时，3D 验证器会系统性误判，而仿真校准又会给它虚假置信；必须以可观测性门控、真机锚点与保守回退为前提，否则“更精细的感知”只会更快地把策略带进沟里。

## 1. 形式化基础

### 1.1 测试期相机位姿从哪里来

接口不传外参，但相机位姿可由本体感觉 + 离线标定恢复：

```
ξ_head(t)  = T_base←torso(q_waist(t)) · T_torso←head
ξ_wrist(t) = T_base←ee(q_arm(t))      · T_ee←wrist
```

- `q_waist(t)` 来自接口的 `observation.state.lower_body`（15 维含 waist）。
- `q_arm(t)` 来自 `observation.state.left_arm/right_arm`。
- `T_torso←head` 用数据集的 `state_d435` 离线拟合/标定；`T_ee←wrist` 用离线手眼标定。
- 数据集的 `head_stereo_left/right` 已整流，若接口的 `cam_left_high/cam_right_high` 就是这对双目（**待核实**），则立体匹配只需视差；否则按未标定双目，用自标定 + 运动恢复结构。

**关键区分**：头部 D435 是**可动**的（数据里有 `action_d435` 目标位姿）。因此单目画面变化有三种来源：物体动、相机自身动、遮挡。只用 2D 外观判 `regressed`，三者不可分。

### 1.2 多视角状态估计与可观测性门控

设视角 `v` 的投影 `π_v(·; ξ_t)`，观测 `I_t^v`，前端输出 `f_v(I_t^v)`（2D 关键点/物体框/接触点）。状态估计：

```
Ŝ_t = argmin_S  Σ_{v∈U_t} ρ( || π_v(S; ξ_t) - f_v(I_t^v) ||_{Σ_v} )
                 + λ || S - S_{t-1} ||²
```

`U_t` 不是“所有可见视角”，而是**可观测性门控后的子集**。对一维进度 `q`，视角灵敏度

```
s_v(q) = || ∂π_v(S(q); ξ_t) / ∂q || / depth
```

门控规则：`s_v(q) ≥ s_min` 才纳入 `U_t`；若 `U_t=∅`，保持上一个可信状态并请求下一帧，而不是硬猜。理由：若运动方向与视线平行，`s_v≈0`，该视角对 `q` 的 Fisher 信息退化；把它硬融进来只会把像素噪声放大成“进度跳变”。

### 1.3 进度谓词与“撤回”判定

每个计分步 `g` 配一个几何谓词 `φ_g(S_t)`：

```
P_g(S_t) = 1[ φ_g(S_t) ≥ 0 ]
```

示例（与 32 任务计分表对齐）：

| 任务族 | 几何谓词 `φ_g` |
|---|---|
| 插入类（T10/T26 插头/网线） | 插头端面到插口平面的有符号距离 `−d`；接触后 `insert_depth − d0` |
| 堆叠类（T20/T27 杯/碗） | 上物体底面与下物体支撑面的高度差；水平投影重叠率 |
| 折叠/拉链类（T16/T19） | 角点相对位移 / 拉链头沿轨道的弧长进度 |
| 开合/拧动类（T12/T14） | 盖子相对瓶口的旋转角；锁舌位移 |
| 分拣/放置类（T02/T04/T06） | 物体中心到目标区域的距离；颜色/类别条件 |

撤回判定必须同时满足三个条件，缺一不可：

```
regressed_t = (p_best − p_t > δ_drop)          # 进度显著回退
            ∧ (C_t < ε_consistency)             # 不是估计崩了
            ∧ (conf_t > c_min)                  # 不是低置信
            ∧ (去抖 ≥ 2 帧)                     # 不是瞬时噪声
```

其中 `p_t = Σ_g w_g P_g(S_t)` 是按计分权重加权的进度，`C_t = max_{v∈U_t} ||π_v(Ŝ_t) − f_v(I_t^v)||` 是交叉视角残差。**这条规则把 v2 的“看到下降就重做”改成“几何上确实下降且估计可信才重做”**，直接针对 H1/H2。

### 1.4 虚实迁移的三层与校准

```
观测迁移：  p_real(I|S)  vs  p_sim(I|S)     → 视觉孪生（3DGS/NeRF）
动力学迁移：p_real(S'|S,a) vs p_sim(S'|S,a) → 系统辨识 + 物理孪生
评测迁移：  S_real        vs  S_sim          → 锚点排序校准（UIP-20）
```

评测迁移的形式化：给定真机锚点 `A={(s_i,y_i)}`，学校准 `g_θ`，优化排序风险

```
R(g_θ) = 1 − ρ_Spearman( g_θ(s), y )
```

并给出不确定集 `U`（conformal 或 bootstrap）。分层先验：

```
θ_t = θ_group(t) + ε_t,   ε_t ~ N(0, τ²)
θ_group ~ N(θ_global, σ²)
```

组效应向全局收缩；**只有交叉验证排序风险显著优于 raw 时才启用校准**。没有足够锚点时，保留 raw 仿真排名并标注不确定度。

### 1.5 五个可由形式化直接推出的结论

1. **单目深度退化视角对进度不可辨识**，用它做撤回检测必然高误报（P1 中 head-only AUC≈0.5、检测率 0、但一旦有噪声就会误报）。
2. **多视角是“条件增益”而非“无条件增益”**：只有纳入非退化视角才提升；硬融退化视角会比最好的单视角更差（P1 中 naive fusion 与 best-single 同为 0.743，且有 80/80 误报）。
3. **校准是“条件增益”**：锚点少/组内样本少时，全局仿射会把噪声当偏差；分组校准更差（P2）。
4. **可观测性门控 + 保守回退**是比“更强分类器”更高杠杆的修复；这直接支撑 UIP-19。
5. **多视角的实时成本必须进入目标函数**：视角数、分辨率、堆叠帧、块长共同决定延迟；不能默认全开（UIP-18）。

## 2. 旗舰深潜：UIP-16 · MV-PVR（Multi-View Progress-Verification with Regression detection）

### 2.1 机制

1. **相机位姿恢复**：由 `lower_body`/`arm` 本体感觉 + 离线 `T_torso←head`、`T_ee←wrist` 计算 `ξ_t`。
2. **视角选择**：按 `s_v(q)` 门控，保留 `U_t`；若 `U_t` 为空，保持上帧状态并请求下一帧（不硬猜）。
3. **3D 状态估计**：多视角联合优化 `Ŝ_t`（关键点/物体位姿/夹爪/接触），输出 `p_t`、`C_t`、`conf_t`。
4. **状态机**：`ongoing / done / fail / regressed`；`regressed` 触发“重做当前子目标”，并受 `max_redo` 与延迟预算约束。
5. **与计分表对齐**：`P_g` 直接复用 v2 的 32 任务计分点（UIP-02′），保证“保前置、搏末步”。

### 2.2 伪代码

```python
class MVPVRPolicy:                       # UIP-16 + UIP-18 + UIP-19
    def __init__(self, policy, geo, calib, task, cfg):
        self.policy = policy
        self.geo = geo                   # 多视角几何/轻量前端
        self.calib = calib               # 离线标定 + 本体感觉→相机位姿
        self.task = task
        self.cfg = cfg                   # sens_min, delta_drop, conf_min, ...
        self.reset()

    def reset(self):
        self.policy.reset()
        self.t = 0
        self.g = 0                       # 当前计分步
        self.redo = 0
        self.p_best = 0.0
        self.prev_S = None
        self.buf = []

    def get_action(self, obs):
        xi = self.calib.camera_poses(obs)          # 不含外参，靠本体感觉
        views = self._select_views(obs, xi)         # UIP-18: 视角/分辨率预算
        S_hat, C, conf = self.geo.estimate(views, xi, self.prev_S)
        p, done = self.geo.progress(S_hat, self.task, self.g)

        # 1) 只有“几何上回退 + 估计可信”才判 regressed
        regressed = (self.p_best - p > self.cfg.delta_drop and
                     C < self.cfg.eps_consistency and
                     conf > self.cfg.conf_min)
        # 2) 统计规律性/延迟护栏（UIP-19）
        if self._reality_gap_high(obs, S_hat, C):
            self.cfg.k = max(1, self.cfg.k // 2)    # 更频繁重观测
            self.cfg.allow_last_step_gamble = False

        if regressed and self.redo < self.cfg.max_redo:
            self.g = max(0, self.g - 1)             # 重做上一个/当前子目标
            self.redo += 1
            self.buf = []                           # 丢弃旧动作块
        elif done:
            self.g = min(self.g + 1, self.task.n_steps - 1)
            self.redo = 0
            self.buf = []
        elif self.redo >= self.cfg.max_redo:
            self.redo = 0                           # 放弃重做，继续保守推进

        self.p_best = max(self.p_best, p)
        if not self.buf or self.t % self.cfg.k == 0:
            self.buf = list(self.policy.get_action(obs, self.cfg.k))[:self.cfg.k]
        self.t += 1
        self.prev_S = S_hat
        return self.buf.pop(0)
```

### 2.3 关键设计选择

- **几何前端不引入外部大模型**：优先用整流双目视差、PnP/EPnP、关键点检测/跟踪、颜色/深度阈值；需要学习时，从主骨干蒸馏一个小头，保证“单模型”合规。
- **不把“照片差异”当进度**：所有谓词都定义在 3D 量上；照片只用于估计 3D 状态。
- **门控优先于融合**：`s_v < s_min` 的视角直接丢弃；若只剩退化视角，宁可“保持+重观测”，不猜。
- **重做有预算**：`max_redo`、`delta_drop`、`eps_consistency` 与 UIP-18 的延迟预算联动；误报重做的代价 = 步骤分 + 延迟，必须显式建模。

### 2.4 可行性与资源

- 公开数据：4 路视频 + `state_d435` + 手臂/腰部本体感觉，足够做离线标定与几何验证。
- 推理：1 张卡；几何前端 CPU 可跑；多视角图像解码是主要开销（见 UIP-18）。
- 接口：`get_action/reset/metadata` 均在权限内；不需要额外传感器。
- 主要风险：标定误差、视角退化、关键点前端失败 → 用 UIP-19 监控 + 2D 回退。

## 3. 次旗舰：UIP-17 · MV-DT（Multi-View Dual Digital Twin）

### 3.1 为什么是“双孪生”而不是“一个更像的仿真”

v2 的 H4 已经指出：Gazebo 的**接口/结构忠实度**高于其**视觉/接触保真度**。本轮把它做成两个明确分离的孪生：

- **物理孪生（physics twin）**：G1 29-DoF 固定底座 + Dex1 + 桌面资产的**碰撞几何**；负责接触、插入深度、堆叠关系、计分谓词。不追求照片级外观。
- **视觉孪生（visual twin）**：从真实多视角数据重建的 3DGS/NeRF 场景；负责外观、视角、遮挡、域随机化。**不用它判成功**，只用于感知训练与视角增强。

两者通过**几何锚点**对齐：相机位姿、物体 6D 位姿、桌面平面、关键点。这样“仿真过拟合仿真”可以被监控：如果视觉孪生渲染出的锚点与物理孪生的几何不一致，说明重建/标定有问题。

### 3.2 real2sim2real 流水线

```
真实多视角 episodes
  ├─ 离线标定：head stereo 基线/焦距、T_torso←head、T_ee←wrist
  ├─ 3D 重建：静态场景 3DGS/NeRF + 物体 6D 位姿/尺寸
  ├─ 物理孪生：Gazebo 资产（碰撞用凸包/长方体+接触参数）
  ├─ 系统辨识：用真实 state/action 拟合质量/摩擦/阻尼/延迟
  ├─ 扰动工厂：脚本化“反向撤回”（拧回/翻开/拉开/拿走/挪底座）
  └─ 视角增强：在视觉孪生里渲染新视角/遮挡/光照，生成跨视角一致样本
```

### 3.3 与 v2 的 UIP-12 的差异

- v2 的 DRF 只在 Gazebo 里造“干扰-恢复”动作；本轮额外在视觉孪生里做**视角一致**的渲染，使策略学到“同一 3D 撤回在不同视角下长什么样”。
- v2 的 GSO 只判“结构/顺序”；本轮把“视觉孪生”作为**域适应训练器**，把“物理孪生”作为**结构裁判**，职责不混。
- 新增“锚点一致性检查”：重建的物体尺寸/位姿与真实 `state_d435`/本体感觉不一致时，拒绝该资产进入训练。

### 3.4 风险

视觉重建“看起来很像”但物理参数错，会制造虚假信心。对策：**物理孪生与视觉孪生分开评估**；所有 sim 结论必须经 UIP-20 的锚点校准；报告中明确标注“sim proxy / D-level”。

## 4. 方法学核心：UIP-20 · ARC（Anchor-calibrated Ranking Calibration）

### 4.1 问题

榜单按“平均成功率 + 步骤分”排序，仿真 oracle 给的是 `S_sim`。如果 `S_sim` 与 `S_real` 的关系是任务相关、异方差的，那么“仿真里涨分”不等于“榜单涨分”。需要回答两个问题：

1. **仿真的读数偏了多少？**（校准）
2. **这个读数现在还可信吗？**（门控/不确定度）

### 4.2 算法

```python
def fit_calibrator(anchors, modes=("raw", "global", "group", "hier"),
                   margin=0.0, min_per_group=4):
    # anchors: list of (s_sim, y_real, group_id)
    cv = {m: loo_rank_risk(m, anchors) for m in modes}
    best = min(cv, key=cv.get)
    # 不校准也是候选；只有显著更好才启用
    if best == "raw" or cv["raw"] - cv[best] < margin:
        return RawCalibrator(), {"mode": "raw", "cv": cv}
    # 分组样本不足时退回 global/raw
    if best in ("group", "hier") and min_group_count(anchors) < min_per_group:
        best = "global"
    return fit(best, anchors), {"mode": best, "cv": cv,
                                "per_group": group_counts(anchors)}
```

- **分层收缩**：`θ_t = θ_group(t) + ε_t`，组效应向全局收缩；`hier` 是组预测与全局预测的加权。
- **门控**：交叉验证（leave-one-anchor-out）选择；若校准不显著优于 raw，保留 raw。
- **不确定度**：对校准后的分数做 bootstrap/conformal 区间；区间过宽时，不把该任务用于“末步搏分”的决策。
- **锚点选择**：按技能组 + 难度分层贪心选点，优先覆盖高权重/高难度任务（T05/T09/T10/T12/T14/T16/T28/T29）。

### 4.3 本轮 D-level 结果（P2）

合成 32 任务、8 组、每组 4 任务；`s = α_t y + β_t + noise`，`α/β` 随组/任务变化。指标=留出任务的 Spearman ρ（越高越好）。

| 场景 | raw | global | group | hier | gated | oracle |
|---|---:|---:|---:|---:|---:|---:|
| gap 低（0.25） | **0.9743** | 0.9743 | 0.9563 | 0.9634 | 0.9718 | 0.9770 |
| gap 中（1.0） | **0.8149** | 0.8149 | 0.7917 | 0.8029 | 0.8115 | 0.8323 |
| gap 高（2.0） | **0.5956** | 0.5507 | 0.5308 | 0.5433 | 0.5527 | 0.6280 |
| 高 gap、16 锚点、4 组 | 0.6330 | 0.6279 | 0.6419 | **0.6739** | 0.6502 | 0.7456 |
| 中 gap、6 锚点 | **0.8194** | 0.7971 | 0.7811 | 0.7888 | 0.8030 | 0.8273 |
| 中 gap、16 锚点 | **0.8110** | 0.8110 | 0.7451 | 0.7775 | 0.8025 | 0.8462 |

**读表（重要，含负结果）**：

1. **锚点少时，校准会伤排序**：中/高 gap 下 raw 反而最好；全局/分组校准把估计噪声当成了偏差。
2. **只有当每组锚点足够（≈4 个/组）且 gap 大时，分层收缩才显著优于 raw**（0.674 vs 0.633）。这给出可执行约束：**没有 ≥4 锚点/技能组，就不要做分组校准**。
3. **门控校准（gated）在锚点稀缺时只能接近 raw，无法稳定超过 raw**；它的价值是“避免更差”，不是“保证更好”。
4. 因此 UIP-20 的正确用法不是“无脑校准”，而是：**先诊断 gap、再决定是否校准、始终报告不确定度**。在锚点不足时，raw + 区间比“精确的错误”更好。

> 注意：本玩具中 `α/β` 与 `y` 独立，raw 已经保序；真实仿真偏差可能与任务难度相关，校准的潜在收益更大。本实验只证明**负迁移风险**与**锚点预算约束**，不证明真实收益。

## 5. UIP-18 · MV-VBS：视角-块长-分辨率联合预算

### 5.1 机制

`metadata` 在握手时定死，但 `get_action` 每次可以返回 ≤ 声明块长的动作；视角/分辨率/堆叠由 `obs_delta_indices` 与 `image_resize` 决定。把实时性写成约束优化：

```
minimize    Σ_t  [ α·E[latency_t] + β·Var[latency_t] + γ·Risk_t ]
subject to  views ⊆ {head_L, head_R, wrist_L, wrist_R}
            r_v ∈ {480×640, 320×240, 240×320, ...}
            stack_v ∈ {1, 2, 4}
            k ≤ K_MAX,   latency_t ≤ L_budget
```

- **角色分解**：头部双目→布局/公制深度/大范围；腕部→接触/细操作。接触密集步（插入/合盖/拉链）优先腕部 + 小 `k`；搬运/布局步优先头部 + 大 `k`。
- **分辨率**：`image_resize` 把 480×640 降到 320×240 或 240×320；立体匹配仍可用，但带宽/解码降数倍。
- **堆叠**：多帧堆叠=多张 JPEG；除速度估计外，默认 `stack=1`，需要时只对腕部堆 2 帧。
- **训练期**：随机丢弃视角 + 跨视角蒸馏，保证“某一路掉了”时策略不崩。

### 5.2 与 UIP-13 的差异

v2 的 ACS 只调 `k`；本轮把“发几张图、多大、堆几帧”与 `k` 一起决策。多视角的实时成本是 O(视角数 × 分辨率 × 堆叠)，必须显式进入目标函数，否则 UIP-16 的精度会被延迟吃回去。

### 5.3 默认配置（锚点未定时）

若 metadata 只能定一次且无法按任务切换：头部双目 320×240 + 当前操作臂腕部 320×240，`stack=1`，`k=4–8` 随阶段在运行期返回 ≤K_MAX 的块；其余视角不声明，避免无谓 JPEG。

## 6. UIP-19 · RG-Mon：reality-gap 监控与保守回退

### 6.1 监控量

- **特征域差异**：`MMD(φ_real, φ_sim)`，`φ` 用 UIP-16 的 3D 状态/接触/进度特征，而不是原始像素。
- **交叉视角残差**：`C_t` 持续偏高 = 几何估计不可信。
- **动作-状态不一致**：实际状态变化与仿真预测的偏差（用真实 state 轨迹校准过的预测器）。
- **延迟/抖动**：README §6 明确记录；异常时降低 `k`、减少视角、避免重试风暴。

### 6.2 回退策略

```
if gap_score > τ_gap:
    k ← max(1, k//2)                  # 更频繁重观测
    use_wrist_view_for_contact = True # 接触步优先近景
    allow_last_step_gamble = False    # 不搏末步
    max_redo = 1                      # 限制重做
    verifier_mode = "conservative"    # 只在高置信时判 done/regressed
```

这把 v2 的“可信度安全阀”从“延迟护栏”升级为“分布外检测 + 行为降级”。

### 6.3 与 UIP-16 的关系

UIP-16 负责“怎么看得更准”，UIP-19 负责“什么时候不该相信自己的眼睛”。二者是精度与安全的配对，不能只做前者。

### 7.1 本轮已完成的 D-level 机制检验（P1）

`exp/mvst_sim.py` 的 P1：合成 3D 物体沿已知路径运动，两个已标定视角；头部视角几乎沿运动方向（深度退化），腕部视角侧视但接触期常被遮挡；含真实撤回与无撤回 episode。指标=frame AUC、平均检测延迟、误报 episode 数（160 个 episode 中 80 个无撤回）。

| 检测器 | AUC | 平均延迟（帧） | 检出率 | 无撤回 episode 误报 |
|---|---:|---:|---:|---:|
| head-only | 0.4949 | 7.00 | 0.00 | 0 / 80 |
| wrist-only | 0.8228 | 0.88 | 1.00 | 0 / 80 |
| best-single（有腕用腕，否则头） | 0.7433 | 0.01 | 1.00 | **80 / 80** |
| naive 多视角（直接联合所有可见视角） | 0.7433 | 0.01 | 1.00 | **80 / 80** |
| **门控多视角（UIP-16）** | **0.8228** | **0.88** | **1.00** | **0 / 80** |

**读表**：

1. **head-only 完全不可用**：深度退化视角对进度几乎不敏感（AUC≈0.5、检出率 0），但一旦有噪声就会误报；这验证了“单目 2D 进度不可观测”。
2. **naive 多视角会负迁移**：它与 best-single 一样，在腕部被遮挡时信任退化的头部视角，导致 80/80 无撤回 episode 全部误报；AUC 从 0.823 掉到 0.743。
3. **门控多视角恢复腕部单视角的性能并消除误报**：AUC 0.8228、延迟 0.88、误报 0/80。它的价值不是“超过最好的单视角”，而是**在视角丢失/遮挡时仍保持可信**；这正是真实部署最需要的鲁棒性。
4. 该实验是合成的、无图像、无真机；只验证机制与失败模式，不作为 UniBot 性能证据。

### 7.2 结论如何改变设计

- UIP-16 必须内置 `s_v` 门控与 `C_t` 置信门；否则“多视角”会成为误报源。
- UIP-19 的 reality-gap/可观测性监控不是可选附件；当 `U_t=∅` 时必须有保守策略。
- UIP-20 必须带“raw 也是候选”的门控；锚点不足时不要校准。
- UIP-18 必须把视角数/分辨率纳入延迟预算；多视角的收益只有在延迟可控时才成立。

## 8. 合规、接口与风险

- **单模型合规**：UIP-16 的多视角编码器共享主骨干；几何前端/标定/重建全部离线，不进入推理图。若使用预训练 3D 基础模型做离线重建，需确认规则是否允许“离线工具”；推理期不调用外部 VLM。
- **接口红线**：只声明必要键；`obs_delta_indices` 偏移必须 ≤0 且严格递增；`image_resize` 的键必须先出现在 `obs_delta_indices`；动作形状 `(T_a, …)`、索引 0 先执行；`meta.token` 每步携带；N 端口状态隔离。
- **实时性**：多视角图像解码是主要开销；默认降分辨率、少堆叠、按阶段选视角；监控延迟均值与方差。
- **虚实迁移**：所有 sim 结论标注为 sim proxy；没有真机锚点不宣称 sim-to-real 成功；视觉孪生不用于判成功。
- **标定风险**：外参/手眼误差会直接变成 3D 验证误差；E203 必须给出容差曲线；标定漂移时回退 2D/保守模式。
- **规则未知**：5 轴中的位置/干扰物/背景、评测轮次/时限/控制频率仍待手册；本清单对这些轴只做接口内可做的事。

## 10. 本轮最大风险与押注

**一句话**：最大的风险是“标定/重建看起来成功，但 3D 验证器与仿真 oracle 一起偏”——多视角几何会放大标定误差，锚点校准又会给偏差一个看似精确的区间；必须用可观测性门控、真机锚点、保守回退和“raw 也可选”的校准门控共同约束，否则精细的 3D 感知只会更快地把策略带进沟里。

**→ 本轮押注：UIP-16（门控多视角 3D 验证）× UIP-20（锚点排序校准）组成的“可信感知-可信评测”闭环，由 UIP-17 双孪生提供离线训练/判分、UIP-18/19 保证实时与安全。** 上一轮解决“缺恢复数据”；本轮解决“判断恢复是否发生、以及仿真读数是否可信”——两者相乘，才是可复现的分数提升。
