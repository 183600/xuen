# 第 55 轮（承接第 54 轮 v16 GroundEdge-GenSim+++；灵感循环第 1 轮；本轮灵感：「用户需求分析」×「数据集」）

> 第 54 轮把技能组合推进为“动作剖面 α_S + 鲁棒性谱 ρ + 云边映射 γ_ce”的双证书体系，但证书回答的是“这个技能在动作空间里有多稳”，却没有回答“谁需要它、在什么任务/情境里需要、凭什么证据说它在真实需求上稳”。本轮把 **用户需求分析** 提升为需求测度 μ_D，把 **数据集** 从训练燃料升级为证据测度 ν_D，并在两者之间建立可判定的充分性关系。核心矛盾：H22：显式需求（访谈/问卷）与隐式需求（遥操作/使用日志）系统性错位，需求不是固定清单而是随用户段与情境漂移的分布；H23：数据集规模大不等于证据充分，数据集支持集可能与需求支持集错配，产生“覆盖幻觉”。

## 0. 直觉与动机

**灵感 1（需求是一条测度，不是一张清单）**
直觉：产品文档里的“用户需要机器人抓杯子”只是需求空间里的一个点，真正决定证书权重的是需求在任务 T、情境 C、用户段 U 上的分布 μ_D。访谈得到显式需求 μ_D^s，遥操作/使用日志/工单得到隐式需求 μ_D^r；二者不一致不是噪声，而是“说的”和“做的”之间的系统偏差。做法：把需求分析写成 **双通道测量 + 部分识别**，输出需求证书而不是需求列表；用校准系数 κ_D 显式记录“显式需求有多可信”。

**灵感 2（数据集不是燃料，是证据）**
直觉：训练集越大，只说明模型见过更多样本，不说明它见过**用户真正需要的那部分**。把数据集写成证据测度 ν_D，则“数据够不够”变成“需求测度是否被证据测度支撑”：μ_D 必须关于 ν_D 绝对连续，且密度比 `w = dμ_D/dν_D` 有界；否则存在需求单元没有任何证据，证书在该单元上应直接判为不可部署。有效样本量 n_eff 由密度比的二阶矩决定，而不是由原始样本数 n 决定。

**灵感 3（Kano 分解：must-be 是硬约束，不是权重）**
直觉：把所有需求压成一个加权和，等于允许“平均满意度”交易掉安全底线。用 Kano 模型拆成 must-be（缺了就不可接受）、performance（越多越好）、attractive（惊喜项）：must-be 进入硬约束 H_D，performance 进入 CVaR 风险，attractive 只进入探索/加分。这样用户需求分析不是给证书调参，而是给证书**加约束**；同时按用户段取 CVaR/worst-segment，避免多数用户的高满意度掩盖少数用户段的系统性失败。

**灵感 4（需求加权证书：把 μ_D 推前到动作-鲁棒性空间）**
直觉：第 54 轮的 ρ、α_S 都是在动作空间上定义的；需求通过能力映射 `φ: X → 2^{A×D}` 推前为 `μ_A = φ_# μ_D`。于是可定义需求加权动作剖面 `α_S^D` 与需求风险 `CVaR_α(r_S; μ_D)`。均匀需求 + 全支撑数据时，新证书退化为第 54 轮的证书；否则它显式暴露“高需求但低覆盖/低鲁棒”的单元。证书不再只问“全局最坏”，而问“用户真正会遇到的范围内，最坏的一截有多坏”。

**灵感 5（需求导向的数据飞轮与漂移再证书）**
直觉：数据集构建不应按“随机/均匀/好采”来扩，而应按 **每单位标注成本能降低多少需求加权风险** 来扩：优先补 Δ_req 大、密度比高、must-be 且模型不确定的需求单元。用户需求还会漂移（新场景、新用户段、季节性），因此需要 Wasserstein 漂移监控 + 迟滞 + 金丝雀用户段，只在受影响单元上触发再证书，避免全量重训与证书震荡。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（需求空间与需求测度）**
需求空间 `X = T × C × U`，其中 T 为任务、C 为情境、U 为用户段。需求测度 `μ_D ∈ Δ(X)` 为其上的概率测度；显式需求 `μ_D^s` 来自访谈/问卷/Kano 编码，隐式需求 `μ_D^r` 来自遥操作、使用日志与工单。需求校准 `κ_D = 1 - TV(μ_D^s, μ_D^r)`；当 `κ_D < θ_κ` 时，需求证书只允许使用 `μ_D^r` 并标记“需求未校准”。

**定义 122（需求证书）**
`R_cert = (μ_D, H_D, w_D, κ_D, U)`：
- `H_D ⊆ X` 为 must-be 需求单元（硬约束）；
- `w_D : X → [0,1]` 为 performance 需求权重；
- `κ_D` 为显式-隐式需求校准度；
- `U = {u_1,...,u_m}` 为用户段划分。

attractive 需求不进入证书约束，只进入探索预算。

**定义 123（数据集证据测度）**
数据集 `D = {(x_i, y_i, p_i, q_i)}_{i=1}^n`，`p_i` 为来源/溯源权重，`q_i ∈ [0,1]` 为质量分。证据测度
```
ν_D = (Σ_i p_i q_i δ_{x_i}) / (Σ_i p_i q_i)
```
有效样本量 `n_eff = (Σ_i w_i)^2 / Σ_i w_i^2`，其中 `w_i = p_i q_i`；`n_eff` 而非 n 决定证书的统计置信半径。

**定义 124（需求-数据充分性）**
若 `μ_D` 关于 `ν_D` 绝对连续，定义密度比 `w(x) = dμ_D/dν_D(x)` 与上界 `B = ||w||_∞`。需求-证据缺口
```
Δ_req(D, μ_D) = μ_D(X \ supp_ε(D))
```
**覆盖幻觉**：`|supp(D)|` 很大但 `Δ_req > Θ_req`，或 must-be 单元 `H_D` 上存在 `ν_D` 零测集。数据集证书 `D_cert = (ν_D, w, B, n_eff, Δ_req, q̄)`；仅当 `Δ_req ≤ Θ_req`、`B ≤ Θ_B`、`n_eff ≥ n_min` 时 D 对 μ_D **充分**。

**定义 125（需求加权联合证书）**
能力映射 `φ: X → 2^{A×D}` 把需求单元映射为所需动作-鲁棒性区域，`μ_A = φ_# μ_D`。对技能序列 S，单元风险 `r_S(x) = 1 - Π_{s∈S} ρ_s(φ(x))` 与需求风险
```
CVaR_α(r_S; μ_D) = min_η { η + 1/(1-α) E_{μ_D}[(r_S - η)_+] }.
```
联合证书扩展为
```
J_D = (ρ_D, α_S^D, A_cert, R_cert, D_cert, γ_ce, δ_a, CVaR_α, evidence)
```
其中 `ρ_D(x) = E_{μ_D}[ρ_S(x)]`，`α_S^D(a) = E_{μ_D}[α_S(a | φ(x))]`。若 `max_{x∈H_D} r_S(x) ≤ 1-ρ_min` 且 `CVaR_α(r_S; μ_D) ≤ 1-ρ_min` 且 `Δ_req ≤ Θ_req`，则 `dom_{J_D}(T) = in`。当 μ_D 为均匀测度且 `Δ_req=0` 时退化为第 54 轮证书。

**定义 126（需求漂移与再证书）**
在窗口 τ 上定义需求漂移
```
drift_t = W_1(μ_D^t, μ_D^{t-τ}),
```
其中 W_1 为 1-Wasserstein 距离。再证书策略 `Π_re = (Θ_drift, k, Hys, U_c)`：连续 k 个窗口 `drift_t > Θ_drift` 才触发，且只在受影响单元与金丝雀用户段 `U_c` 上重证；`Hys` 为迟滞带，防止证书震荡。

## 2. 关键算法 伪代码

### IP-121 DPE（Demand Profile Elicitation）

```python
def elicit_demand(interviews, tickets, teleop, usage, X):
    mu_s = stated_measure(interviews, tickets, X)   # Kano 编码后的显式需求
    mu_r = revealed_measure(teleop, usage, X)        # 行为/日志的隐式需求
    kappa = 1.0 - total_variation(mu_s, mu_r)
    # 部分识别：低校准时以隐式需求为锚，显式需求只作先验
    if kappa < THETA_KAPPA:
        mu = mu_r
    else:
        mu = wasserstein_barycenter(mu_s, mu_r, kappa)
    return DemandCert(mu, kappa)
```

### IP-122 KDD（Kano Demand Decomposition）

```python
def kano_decompose(requirements):
    H, P, A = set(), {}, set()
    for r in requirements:
        cat = classify_kano(r)          # must-be / performance / attractive
        if cat == 'must_be':
            H.add(r.cell)
        elif cat == 'performance':
            P[r.cell] = r.importance
        else:
            A.add(r.cell)
    return H, normalize(P), A
```

### IP-123 DSE（Dataset Sufficiency Estimator）

```python
def dataset_sufficiency(D, mu_D, phi, quality_model):
    nu = empirical_measure([phi(x) for x in D.x], weights=D.pq)
    support = conservative_support(D, phi, conf=0.95)   # 保守支持集
    delta_req = mu_D(X_minus(support))
    w = density_ratio(mu_D, nu, support)                # 仅在支撑处估计
    B = max(w.values()) if w else float('inf')
    n_eff = effective_sample_size(D.pq)
    q_bar = quality_model(D)
    return DatasetCert(nu, w, B, n_eff, delta_req, q_bar)
```

### IP-124 RDA（Requirement-Dataset Alignment）+ DDC（Demand-Directed Curation）

```python
def align_and_curate(mu_D, D, phi, budget, H_D):
    cert = dataset_sufficiency(D, mu_D, phi, quality_model)
    pool = candidate_pool()
    while budget > 0 and (cert.delta_req > THETA_REQ or cert.n_eff < N_MIN):
        # 需求加权增益 / 标注成本；must-be 单元给无穷权重
        def gain(x):
            w = INF if x.cell in H_D else mu_D(x.cell) * cert.density_ratio(x.cell)
            return w * uncertainty_gain(x) / label_cost(x)
        x = max(pool, key=gain)
        D = D | label(x)
        pool.remove(x)
        budget -= label_cost(x)
        cert = dataset_sufficiency(D, mu_D, phi, quality_model)
    return cert, D
```

### IP-125 DAC（Demand-Aware Certification）

```python
def demand_aware_cert(skill_seq, mu_D, R_cert, D_cert, alpha=0.9, rho_min=0.8):
    mu_A = pushforward(mu_D, phi)
    r = {x: cell_risk(skill_seq, x) for x in support(mu_D)}
    if D_cert.delta_req > THETA_REQ or D_cert.n_eff < N_MIN:
        return ('reject', 'evidence_insufficient', D_cert)
    must_fail = max((r[x] for x in R_cert.H_D), default=0.0)
    cvar = cvar_alpha(r, mu_D, alpha)
    if must_fail > 1 - rho_min or cvar > 1 - rho_min:
        return ('reject', 'demand_risk', must_fail, cvar)
    return ('ok', JointCert_D(rho_D, alpha_D, R_cert, D_cert, cvar))
```

### IP-126 RDM（Requirement Drift Monitor）

```python
def drift_monitor(history, tau, k, Theta_drift, Hys, U_c):
    d = wasserstein1(history[-1], history[-1-tau])
    if d > Theta_drift * (1 + Hys):
        streak += 1
    else:
        streak = 0
    if streak >= k:
        affected = {x for x in support(history[-1]) if cell_shift(x) > Hys}
        return recertify(affected | U_c)   # 只重证受影响单元 + 金丝雀段
    return 'stable'
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| DPE | O((n_s+n_r)·|X|) | O(|X|) | 双通道测量、校准可识别 |
| KDD | O(|R|) | O(|X|) | Kano 分类一致、must-be 不漏 |
| DSE | O(n·|X| + |X| log |X|) | O(n+|X|) | 支持集保守、密度比有界 |
| RDA/DDC | O(B·(n·|X| + T_DSE)) | O(n+|X|) | 增益次模、预算单调 |
| DAC | O(|S|·|X| + |X| log |X|) | O(|X|) | CVaR 单调、must-be 硬约束 |
| RDM | O(|X|²/ε²) 每窗口 | O(|X|²) | W1 度量、迟滞收敛 |

**正确性定理（Demand-Evidence Certification Soundness）**
承接第 54 轮 (A22)–(A28)；新增：
- **(A29) 需求可校准**：`TV(μ̂_D, μ_D^*) ≤ ε_μ`；
- **(A30) 证据保守**：`P(Δ_req ≤ ε_s) ≥ 1-δ_s`，且密度比估计误差 `≤ ε_w`；
- **(A31) 漂移有界**：`W_1(μ_D^{t+τ}, μ_D^t) ≤ δ_drift`，单元风险对 x 的 Lipschitz 常数为 `L_r`。

则部署风险
```
Risk_deploy(J_D) ≤ CVaR_α(r_S; μ_D) + L_r(ε_μ + ε_s + δ_drift)
                    + C·sqrt((1+Var(w))/n) + β_E + P(δ_a > Θ_a)
```
当右端 `≤ 1-ρ_min` 时，需求加权证书 sound；若 μ_D 均匀且 `Δ_req=0`，右端退化为第 54 轮的 `Σ_d(1-ρ_min(d)) + β_E + P(δ_a>Θ_a)`。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 需求诱导偏差、显式≠隐式 | 高 | 多通道三角验证 + 部分识别 + 用户共创 + 分层抽样 |
| 数据支持集高估、覆盖幻觉 | 高 | 保守支持集 + conformal 覆盖 + 留出用户段审计 + 反事实探测 |
| 长尾需求单元不可识别 | 高 | 分层估计 + 贝叶斯收缩 + CVaR + 主动采样 |
| 需求指标被 Goodhart 化 | 中 | 多指标 + 外部审计 + 数据溯源 + 红队 |
| 需求漂移导致证书震荡 | 中 | Wasserstein 监控 + 迟滞 + 金丝雀用户段 |
| 用户日志隐私与合规 | 高 | 最小化采集 + 差分隐私/联邦 + 用途限定 |

## 6. 本轮最大风险

**一句话**：需求-证据底座的 soundness 三重依赖需求测度可校准、数据支持集可保守估计、需求漂移有界；一旦“说的需求”压过“做的需求”、或数据支持集被高估形成覆盖幻觉，证书会以极高的形式严谨性证明错误的东西——它不是算错了，而是从一开始就在为错误的需求和错误的证据背书。

## 2. 关键算法 伪代码

### IP-121 DPE

```python
def stated_measure(interviews, tickets, X):
    # Kano 编码：把一条自然语言需求映射到需求单元 x=(t,c,u)
    # 权重 = 提及频率 × 严重度 × 用户段覆盖
    mu = zeros(X)
    for r in interviews + tickets:
        x = map_to_cell(r, X)
        mu[x] += r.frequency * r.severity * segment_weight(r.user_segment)
    return normalize(mu)

def revealed_measure(teleop, usage, X):
    # 隐式需求：遥操作与使用日志在需求单元上的占用
    # 用逆强化学习/占用频率估计，而不是直接读用户自述
    mu = zeros(X)
    for episode in teleop + usage:
        x = infer_cell(episode, X)
        mu[x] += episode.duration * episode.success_weight
    return normalize(mu)

def elicit_demand(interviews, tickets, teleop, usage, X):
    mu_s = stated_measure(interviews, tickets, X)
    mu_r = revealed_measure(teleop, usage, X)
    kappa = 1.0 - total_variation(mu_s, mu_r)
    if kappa < THETA_KAPPA:
        mu = mu_r                       # 低校准：以行为证据为锚
        status = 'uncalibrated'
    else:
        mu = wasserstein_barycenter(mu_s, mu_r, kappa)
        status = 'calibrated'
    return DemandCert(mu, kappa, status)
```

def kano_decompose(requirements):

### IP-123 DSE

```python
def conservative_support(D, phi, conf=0.95):
    # split-conformal 风格：留出样本估计单元球半径 r_hat
    # supp_eps = ∪_i B(phi(x_i), r_hat)，保证真支持集以 conf 概率被覆盖
    cal, test = split(D)
    r_hat = conformal_radius(cal, test, conf)
    return union_of_balls([phi(x) for x in D.x], r_hat)

def density_ratio(mu_D, nu, support):
    # classifier two-sample test：训练 g 区分需求样本与数据样本
    # w(x) = g(x)/(1-g(x))，在 support 外记为 +inf
    g = train_two_sample_classifier(samples(mu_D), samples(nu))
    w = {x: clip(g(x)/(1-g(x)), 0, W_MAX) for x in support}
    return w

def dataset_sufficiency(D, mu_D, phi, quality_model):
    nu = empirical_measure([phi(x) for x in D.x], weights=D.pq)
    support = conservative_support(D, phi, conf=0.95)
    delta_req = mu_D(X_minus(support))
    w = density_ratio(mu_D, nu, support)
    B = max(w.values()) if w else float('inf')
    n_eff = effective_sample_size(D.pq)
    q_bar = quality_model(D)
    return DatasetCert(nu, w, B, n_eff, delta_req, q_bar)
```

### IP-124 RDA + DDC

```python
def admissible(D_cert, H_D, Theta_req, Theta_B, N_MIN):
    if D_cert.delta_req > Theta_req:
        return False, 'demand_uncovered'
    if D_cert.B > Theta_B:
        return False, 'density_ratio_too_large'
    if D_cert.n_eff < N_MIN:
        return False, 'effective_sample_too_small'
    for x in H_D:
        if D_cert.nu(x) <= 0:
            return False, 'must_be_unsupported'
    return True, 'ok'

def align_and_curate(mu_D, D, phi, budget, H_D):
    cert = dataset_sufficiency(D, mu_D, phi, quality_model)
    pool = candidate_pool()
    while budget > 0 and not admissible(cert, H_D, THETA_REQ, THETA_B, N_MIN)[0]:
        def gain(x):
            # must-be 单元优先；其余按需求质量 × 密度比 × 不确定度 / 成本
            if x.cell in H_D:
                w = INF
            else:
                w = mu_D(x.cell) * cert.density_ratio.get(x.cell, 1.0)
            return w * uncertainty_gain(x) / label_cost(x)
        x = max(pool, key=gain)
        D = D | label(x)
        pool.remove(x)
        budget -= label_cost(x)
        cert = dataset_sufficiency(D, mu_D, phi, quality_model)
    return cert, D
```

### IP-125 DAC

```python
def cell_risk(skill_seq, x):
    # 单元风险 = 1 - 技能链在该需求单元对应动作-鲁棒性区域上的存活概率
    p = 1.0
    for s in skill_seq:
        p *= robustness_spectrum(s, phi(x)).min()
    return 1.0 - p

def cvar_alpha(r, mu_D, alpha):
    # Rockafellar-Uryasev：CVaR 的凸表示，可直接线性规划
    return min(eta + (1.0/(1.0-alpha)) * sum(mu_D[x]*max(r[x]-eta, 0)
                                              for x in r)
               for eta in candidate_etas(r))

def demand_aware_cert(skill_seq, mu_D, R_cert, D_cert,
                      alpha=0.9, rho_min=0.8):
    ok, why = admissible(D_cert, R_cert.H_D, THETA_REQ, THETA_B, N_MIN)
    if not ok:
        return ('reject', 'evidence_insufficient', why)
    r = {x: cell_risk(skill_seq, x) for x in support(mu_D)}
    must_fail = max((r[x] for x in R_cert.H_D), default=0.0)
    cv_a = cvar_alpha(r, mu_D, alpha)
    if must_fail > 1.0 - rho_min:
        return ('reject', 'must_be_violation', must_fail)
    if cv_a > 1.0 - rho_min:
        return ('reject', 'demand_tail_risk', cv_a)
    return ('ok', JointCert_D(
        rho_D=weighted_rho(skill_seq, mu_D),
        alpha_D=weighted_alpha(skill_seq, mu_D),
        A_cert=action_certificate(skill_seq),
        R_cert=R_cert, D_cert=D_cert,
        cv_a=cv_a, evidence=evidence_chain(skill_seq, D_cert)))
```

def drift_monitor(history, tau, k, Theta_drift, Hys, U_c, state):
    d = wasserstein1(history[-1], history[-1-tau])   # Sinkhorn 近似
    state.streak = state.streak + 1 if d > Theta_drift*(1+Hys) else 0
    if state.streak < k:
        return 'stable'
    affected = {x for x in support(history[-1])
                if cell_shift(x, history[-1], history[-1-tau]) > Hys}
    # 只重证受影响单元 + 金丝雀用户段，避免全量重训与证书震荡
    return recertify(affected | U_c, hysteresis=Hys)

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| DPE | O((n_s+n_r)·|X|) | O(|X|) | 双通道可识别、校准 `κ_D` 单调 |
| KDD | O(|R|) | O(|X|) | Kano 分类一致、must-be 不漏 |
| DSE | O(n·|X| + |X| log |X|) | O(n+|X|) | 支持集保守、密度比有界 |
| RDA/DDC | O(B·(n·|X|+T_DSE))（lazy greedy 可降） | O(n+|X|) | 增益次模、预算单调、must-be 优先 |
| DAC | O(|S|·|X|+|X| log |X|) | O(|X|) | CVaR 凸、must-be 硬约束 |
| RDM | O(|X|²/ε²) 每窗口 | O(|X|²) | `W_1` 度量、迟滞收敛 |

**正确性定理（Demand-Evidence Certification Soundness）**
承接第 54 轮 (A22)–(A28)；新增：
- **(A29) 需求可校准**：`TV(μ̂_D, μ_D^*) ≤ ε_μ`；
- **(A30) 证据保守**：`P(Δ_req ≤ ε_s) ≥ 1-δ_s`，密度比估计误差 `≤ ε_w`；
- **(A31) 漂移有界**：`W_1(μ_D^{t+τ}, μ_D^t) ≤ δ_drift`，单元风险对 x 的 Lipschitz 常数为 `L_r`。

则部署风险
```
Risk_deploy(J_D) ≤ CVaR_α(r_S; μ_D) + L_r(ε_μ + ε_s + δ_drift)
                    + C·sqrt((1+Var(w))/n) + β_E + P(δ_a > Θ_a)
```
当右端 `≤ 1-ρ_min` 时，需求加权证书 sound。

**退化为第 54 轮**：取 `μ_D = Unif(X)`、`Δ_req = 0`、`κ_D = 1`、`δ_drift = 0`，则 `CVaR` 退化为最坏维度风险，右端回到 `Σ_d(1-ρ_min(d)) + β_E + P(δ_a>Θ_a)`。这说明本轮不是推翻第 54 轮，而是把“均匀假设”替换为“可审计的需求测度”。

**关键引理**
1. **覆盖引理**：若 `Δ_req ≤ ε_s`，则未被证据支撑的需求质量不超过 ε_s；must-be 单元零支撑直接否决。
2. **密度比引理**：在 `B ≤ Θ_B` 下，重要性加权估计的方差满足 `Var ≤ B²/n_eff`；因此 n_eff 而非 n 控制置信半径。
3. **CVaR 引理**：`CVaR_α` 对 μ_D 的 `W_1` 扰动满足 Lipschitz 界 `|CVaR(μ)-CVaR(μ')| ≤ L_r·W_1(μ,μ')`，这是漂移再证书阈值的理论依据。

## 4. 需求分析操作化（Kano → 证书）

| Kano 类别 | 用户语言 | 形式角色 | 证书处理 |
|---|---|---|---|
| must-be | “不能没有/坏了就不能用” | 硬约束集 `H_D` | `max_{x∈H_D} r_S(x) ≤ 1-ρ_min`，一票否决 |
| performance | “越快/越准/越稳越好” | 权重 `w_D` | 进入 `CVaR_α(r_S;μ_D)` |
| attractive | “有这个会惊喜” | 探索集 `A` | 不参与安全证书，只进探索预算与演示 |

## 8. 本轮最大风险

**一句话**：需求-证据底座的 soundness 三重依赖需求测度可校准、数据支持集可保守估计、需求漂移有界；一旦“说的需求”压过“做的需求”、或数据支持集被高估形成覆盖幻觉，证书会以极高的形式严谨性证明错误的东西——它不是算错了，而是从一开始就在为错误的需求和错误的证据背书。
