# 第 3 轮迭代（灵感循环 v3：「人机交互」×「意图识别」）—— 把“人”从扰动源升级为带意图的第二智能体

> **本轮不是再加一个模块，而是换一个建模视角。** 承接 v2（UIP-01′~15）。v2 把 `human_*` 视为“对已完成进度的反向撤回”，本质是把人的动作压缩成一个 `regressed` 布尔量；这抓住了最大数据空白，但也把“人”压扁了。本轮两个词要求把它展开：**人为什么动、动的是哪一类、下一步会动哪里；机器人又该如何在不碰撞、不抢手的前提下，把自己的意图表达清楚。** 结论：v2 的“检测→重做”仍是骨架，但必须升级为 **“归因→识别→预测→让行/恢复”** 的闭环。

---

## 0. 两个直觉（先讲人话）

1. **人机交互的直觉**：人不是随机噪声，而是会“接话”的对手/伙伴。人会在你刚合上时打开、刚叠好时翻开、刚放好时拿走——这是**有条件的、针对已完成子目标的交互**，不是均匀撒下的扰动。因此机器人不能只在事后重做，而要读人的“下一步”，并在人靠近时让开。更关键的是：**接口里没有任何语音/屏幕/文字输出通道，机器人唯一能“表达”的东西就是动作**。所以“礼貌、可读、不吓人”的轨迹本身就是交互协议的一部分，而不是装饰。
2. **意图识别的直觉**：意图至少有两层。**任务意图**是语言指令到底要什么（目标、对象、顺序、约束）；**人的意图**是刚才那一下到底是在撤回、挪动、阻挡、补料还是拿走。两者都不是为了贴标签，而是为了**选动作**：知道是“撤回”就重做；是“挪动”就重定位；是“阻挡”就让行；是“补料”就整合。**搞错类别比不检测更糟**——把“人挪了盘子”误判成“我失败了”，会触发无休止重做，既浪费步骤分又可能撞到人。

## 1. 本轮复核的事实与三处纠偏（2026-11-13）

| 事项 | 复核结果 | 来源 |
|---|---|---|
| 动作块长度 | `action_chunk_size=T_a` 在 metadata 中一次声明；**每个动作数组形状必须严格等于 `(T_a, …)`**，本地校验器逐键检查 | `example/example_env.py` 的 `step()`；README §3 |
| 观测通道 | 4 路相机（左右 high + 左右 wrist）+ 本体关节/末端/夹爪/lower_body + **单条字符串 `observation.language`**；无人类状态、无力/触觉、无深度 | README §2 |

| 输出通道 | 只有动作字典；**没有语音、文本、屏幕或“请求澄清”的通道** | README §3 |
| 多端口 | N 台真机随机顺序；必须暴露 **N 个连续端口**（8765 起），端口数精确等于 N；每端口独立完成全流程，共享后端要处理并发与**每端口状态隔离** | README §5 |
| token | `metadata.token` 握手一次 + 每次动作 `meta.token` 校验；缺失/不匹配即拒 | README §4 |
| 可信度 | 逐步响应延迟及其波动、动作统计规律性会被记录并可能随结果展示 | README §6 |
| 单模型 | **README 本轮仍未出现 “single model” 约束**；它只存在于前两轮引用的手册/传闻中，而飞书手册当前不可读 | README 全文；飞书链接（2026-11-13） |
| 人为干扰 | v2 的 `generalization.human_*` 证据继续有效；但需注意：这些是**离线任务描述**，不是运行时输入，策略在评测时只能从图像/本体/语言里推断 | v2 §0；`tasks_v2/<slug>/info.json` |

**纠偏 A（工程硬约束，必须改 v2）**：v2 的 UIP-13/ACS 说“每次可返回 ≤k 步的块”。这在当前校验器下**不成立**：动作数组形状必须严格等于 `(T_a,…)`，返回短块会被拒。因此 **UIP-13 必须封存/改写**；`T_a` 只能在握手时选一次。真正可做的是：**选一个全局 `T_a` + 把块的内容设计成“可恢复、低承诺”的**（见 UIP-20）。固定开环块是 HCI 的硬约束，不是可忽略的实现细节。

**纠偏 B（HCI 硬约束）**：观测里**没有人类状态、没有力/触觉、没有深度**。所以不能声称“力限柔顺”“精确人手位姿”“握手/递物”这类需要额外传感的交互；安全让行只能基于**视觉占用 + 本体位姿 + 保守速度/距离**。这也意味着“读出人的意图”必须从**状态变化与视觉线索**反推，而不是读心。

**纠偏 C（合规假设降级）**：v2 把“单模型多任务”当硬约束。现在应降级为**未核实假设**：架构应保证“若单模型规则成立仍合规”，但不要为一个可能不存在的限制牺牲全部性能。是否允许外部预训练、闭源 API、合成数据、外部人手检测器，**只能向主办方书面确认**；在此之前，默认用**共享骨干 + 规则/轻量头**的保守方案。

**由事实直接推出的新空白**：官方没有说明 (i) 人是否会在**块执行中途**干预；(ii) 人干预的**类型分布**与**触发时机**；(iii) 语言指令的具体措辞是否覆盖全部 32 任务。前两项决定“开环块内盲区”的风险，第三项决定“语言意图解析”能做到多深。**本轮把它们都作为待验证假设，而不是既成事实。**

## 2. 两个灵感词的严格定义（先直觉，后形式）

### 2.1 人机交互：把评测建模成“混合自主的回合制交互”

**直觉**：这不是“机器人在一个干净环境里做任务，偶尔有人碰一下”，而是“**人和机器人共享同一个工作空间，人的动作会根据机器人的进度而变化**”。人是有记忆、有目标、会等待时机的；机器人则被锁在一个固定长度的开环块里，只能在块边界“抬头看”。

**形式定义**：一个 episode 是一个二元交互过程 `(π, H)`：

- 机器人策略 `π` 在块边界接收 `o_t = (I_t^{1:4}, q_t, l)`，输出 `A_t = (a_{t,1},…,a_{t,T_a})`，评测端**整块执行**后才再次调用。
- 人类干预者 `H` 有一个隐藏意图 `h_t ∈ ℋ` 和一个**进度条件干预策略** `π_H(h_t | X(t), history)`，其中 `X(t)` 是当前已完成子目标集合。人可以在任意时刻（包括块中途）改变环境。
- 机器人唯一表达通道是动作；没有语言/屏幕/请求澄清。
- 目标是最大化 `E[Σ_g w_g X_g(T)]`（步骤分 + 成功率），同时满足**安全约束**（不碰撞、不夹人、不把物体扫向人）与**可信度约束**（延迟稳定、动作统计不异常）。

**关键性质（本轮的核心洞察）**：干预是**进度条件**的，不是平稳噪声。因此一个计分步的价值不只是“能否达成”，而是 **“达成后能否活到 episode 结束”**。这把 v2 的“检测到 regressed 就重做”从**反应式**升级为**预测式 + 耐久性调度**（见 §3、产物区 §1）。

**交互的表达面**：由于没有语言通道，“可读性”只能通过**运动**实现：接近前减速、抓取前对准、避让人手时走弧线、恢复前先退回安全位。这些不直接加分，但会降低碰撞/无效 episode/可信度异常的概率——在有人参与的评价里，**安全与可信度本身就是分数的一部分**。

### 2.2 意图识别：两层意图，都是“为决策服务的后验”

**直觉**：意图识别不是给每帧打一个标签，而是维护“我现在该不该动手、该动哪只手、该等多久”的信念。任务意图告诉你“做什么”，人的意图告诉你“刚才发生了什么、接下来会不会再发生”。

**形式定义**：

1. **任务意图（task intent）**：把语言 `l` 解析成类型化目标图 `G=(V,E,Φ)`：
   - `V`：对象/角色节点，带属性（类别、颜色、形状、可抓部位）；
   - `E`：关系与顺序边（`on`, `in`, `left_of`, `stacked_on`, `inserted_into`, `zipped`, `folded`…）；
   - `Φ`：约束（哪些步有先后、哪些步末步分值更高、哪些物体不能被遮挡）。
   32 任务与计分点是公开的，因此可以用**任务库 + 语言路由**来初始化 `G`；未见物体通过属性匹配到角色，而不是匹配到固定实例。

2. **人的意图（human intent）**：定义干预类型集合
   ```
   ℋ = {∅, W, D, O, S, R}
   W=撤回/反向（undo）  D=位移/重定位（displace）
   O=阻挡/占位（obstruct） S=补料/接入（supply）
   R=拿走/移除（remove）  ∅=无干预
   ```
   机器人看不到 `h_t`，只能看到 `o_t` 和自身动作 `a_t`。用**因果归因后验**近似：
   ```
   b_t(h) = P(h_t = h | o_{1:t}, a_{1:t})
   ```
   更新：
   ```
   b_{t+1}(h) ∝ P(o_{t+1} | h, o_t, a_t) · Σ_{h'} P(h | h') b_t(h')
   ```
   其中观测似然由“**残差 + 语义模板**”给出：先用前向模型 `f(o_t,a_t)` 预测机器人单独作用下的下一帧，得到残差 `r_{t+1}=o_{t+1}-f(o_t,a_t)`；再用干预模板匹配残差的结构（见产物区 §2、§3.1）。

3. **预测（forecast）**：真正有用的不是“刚才是什么”，而是“下一个块里会不会发生、发生在哪个子目标上”。定义**进度条件风险率**：
   ```
   λ_h(g,t) = lim_{Δt→0} P(下一个 Δt 内发生 h 型干预，且目标为子目标 g | X(t), b_t, 人手距离…)
   ```
   这是 UIP-16 的核心；它把“事后重做”变成“事前调度 + 事中让行”。

**为什么这两层要合在一起**：任务意图给出“哪些步值得保、哪些步可以牺牲”；人的意图给出“这些步会被谁、以什么方式、在什么时候破坏”。二者相乘，才得到 v3 的**耐久性加权步骤分**（§3.2）。只做任务意图，会盲目追求完成；只做人的意图，会陷入被动救火。

## 3. 瓶颈假设（更新）

- **H1（最高杠杆）**：`human_*` 干预是**进度条件且类型多样**的；v2 的“一律 `regressed`→重做”在 `D/O/S` 类型上会**误动作**（把挪动当撤回、把阻挡当失败），既浪费步骤分又增加碰撞风险。**类型化响应的收益大于单纯提高检测灵敏度。**
- **H2**：**因果归因**是主导误差源。自身执行失败、物理滑落、人的撤回在视觉上可能相似；不做归因就会把“我失败了”和“人改了”混为一谈，导致重做死循环或该重做时不重做。
- **H3**：`T_a` 固定意味着**块内盲区**不可消除。块越长，单次延迟越低，但人对块中途的干预越不可见；块越短，反应越快，但往返延迟与方差越大。**这是实时性与交互安全性的直接权衡，必须用“低承诺块”来缓解，而不是幻想运行期改 `T_a`。**
- **H4**：语言是唯一任务意图通道，但可能很简短/模板化；未见物体与背景泛化要靠**属性化目标图 + 场景证据**，不能靠记忆任务名。若语言歧义，只能做**认知性动作**（移动到更好视角、暂停观察），不能“问人”。
- **H5**：安全/可读性不是分数的对立面。一次碰撞、一次夹手、一次 episode 被判无效，可能吞掉所有步骤分收益；在有人干扰的任务里，**让行（yield）通常是期望损失最小的控制**。

## 4. 候选与合并 → v3 清单（详见产物区）

围绕两个词发散，得到以下调整：

- **旗舰升级**：**UIP-01″ RHPVI-D**（Rolling-Horizon Progress-Verified with Intent & Disturbance）——在 v2 的 `done/ongoing/fail/regressed` 上增加**归因**与**人类意图后验**，输出不再是“重做/不重做”，而是 `{proceed, guard, yield, redo, replan}`。
- **升级**：**UIP-09″ HIIR**（Human-Intent-aware Intervention Recovery）替代 v2 的无差别 DCR-R；**UIP-14 MSGR** 改为**任务意图 + 人的意图联合路由**；**UIP-15 CSG** 增加人类安全包络；**UIP-11/12** 扩展为带人类代理与意图标签的 GSO-I / DRF-I。
- **合并**：UIP-05（语言→可供性分解）并入 **UIP-19 LIG**（语言意图接地），避免两套语言解析。
- **封存/改写**：**UIP-13 ACS** 因固定 `T_a` 不可实现，改写为 **UIP-20 ISC**（Intervention-Safe Chunk：固定块长下的低承诺块设计 + 全局 `T_a` 选择）。
- **新增**：**UIP-16 HIFF**（人类干预预测）、**UIP-17 CIA**（因果干预归因）、**UIP-18 SHY**（安全让行包络）、**UIP-19 LIG**（语言意图接地）、**UIP-20 ISC**（交互安全块）。

**本轮最值得押注的方向**：`UIP-17 CIA`（分清是谁改的）× `UIP-16 HIFF`（预测何时/哪类干预）× `UIP-20 ISC`（固定块长下的安全执行），三者由 `UIP-01″` 统一调度。它瞄准的是 v2 已证明存在、但被“布尔化”处理的最大得分缺口：**人类干预的类型与时机**。

---

## 5. 本轮最大风险

**一句话**：如果“人的意图识别”变成在自造仿真数据上自洽、在真人手里失效的读心器，那么误判会把“挪动”当成“撤回”、把“让行”变成“发呆”，既撞人又死循环——**最大风险不是检测不到干预，而是意图模型的自证偏差**。

## 1. 旗舰深潜：UIP-01″ · RHPVI-D

**全称**：Rolling-Horizon Progress-Verified with Intent and Disturbance。

### 1.1 架构（七层，全部在选手侧/离线）

```
语言 l ──► UIP-19 LIG：目标图 G=(V,E,Φ)
                 │
图像+本体 o_t ──► UIP-17 CIA：残差归因 c∈{robot,human,physics}
                 │           └─► 若 human：UIP-09″ 类型 h∈{W,D,O,S,R}
                 ▼
         进度监视 V(o_t, G, g) ──► X_g(t) ∈ {0,1}
                 │
                 ▼
         UIP-16 HIFF：b_t(h), λ_h(g,t)
                 │
                 ▼
      耐久性调度器（UIP-02′）：选下一个子目标/顺序
                 │
                 ▼
       UIP-20 ISC：生成 T_a 步“低承诺块 + 护栏尾巴”
                 │
                 ▼
       UIP-18 SHY：安全投影（减速/让行/保持）
                 │
                 ▼
            返回动作块 A_t
```

### 1.2 形式化

- 计分步 `g=1..G`，权重 `w_g`，`Σ_g w_g = 100`（或归一化为 1）。`X_g(t)∈{0,1}` 表示第 `g` 步当前是否满足。
- episode 末分数 `S = Σ_g w_g X_g(T)`。
- 人的隐藏意图 `h_t ∈ ℋ={∅,W,D,O,S,R}`；机器人维护后验 `b_t(h)`。
- **耐久性**：若第 `g` 步在 `t_g` 完成，此后被干预撤回的风险率为 `λ_g`，则
  ```
  d_g(t_g) = P(X_g(T)=1 | X_g(t_g)=1, b_{t_g}) ≈ exp(-∫_{t_g}^{T} λ_g(s) ds)
  ```
  若允许重做，则把 `d_g` 看作“首次完成后的存活率”，重做会重置风险但消耗时间。
- **耐久性加权目标**（本轮的核心度量修正）：
  ```
  E[S] ≈ Σ_g w_g · P(按计划到达 g) · d_g(t_g)
  ```
  v2 的“保前置、搏末步”只优化了第一项；v3 明确还有第二项 `d_g`。**同样完成所有步，完成得越早，越容易被撤回。**
- **调度问题**：在偏序（目标图 `E`）和时间预算下，选完成顺序 `π` 与时间 `t_{π(i)}`，最大化 `Σ w_{π(i)} P(reach) d_{π(i)}`。`G≤5`，可枚举合法拓扑序 + 小规模 DP/搜索；这是**离线可算、在线可查表**的。
- **安全约束**：动作块 `A_t` 必须落在安全集 `𝒮(o_t)` 内（关节/速度限、人手/人臂占用区之外、不把物体扫向人）；否则投影为保持/后退。形式上是约束 MDP：
  ```
  max_π E[S]   s.t.  A_t ∈ 𝒮(o_t),  latency 稳定,  动作统计不异常
  ```
- **响应映射**（不是布尔重做）：

  | 归因/意图 | 触发线索 | 响应 |
  |---|---|---|
  | 自身失败（robot/fail） | 残差与指令方向一致但未达成；无外来位移 | 小步重试；换抓取位姿；必要时重规划 |
  | `W` 撤回 | 已完成关系回退到完成前；手离开后状态保持回退 | 等手离开→**重做同一子目标**；不要追手 |
  | `D` 位移 | 物体位姿跳变但任务关系未回退 | **重定位**目标位姿，更新 `G`，继续当前步；不重做前置 |
  | `O` 阻挡 | 人手/臂进入可达体积；底座/插口被挪走 | **让行/等待**；退到安全位；人离开后恢复 |
  | `S` 补料 | 新物体/另一端出现 | **整合**（如双端插线）；更新目标图 |
  | `R` 拿走 | 目标物体从工作区消失 | 等待返回；若超时则重规划/放弃该步保前置 |

### 1.3 与 v2 的差异

1. v2 的 `regressed` 是单一布尔；v3 把它拆成 `W/D/O/S/R`，响应从“一律重做”变成“分类响应”。这直接修正 v2 在 `D/O` 任务上的误动作。
2. v2 的验证器只问“达成没有”；v3 同时问“**是不是人改的、接下来还会不会改**”，并把答案送进调度器。
3. v2 的 UIP-13 假设可变块长；v3 承认固定 `T_a`，用 UIP-20 在块**内容**上做文章。
4. v2 把安全当合规附录；v3 把安全/可读性作为**约束**进入主优化。

### 1.4 可行性/资源/风险

- **可行性**：高。语言解析可用模板 + 属性规则；CIA 可用“物体跟踪 + 前向残差 + 语义模板”，不依赖外部大模型；HIFF 可用小型风险头或规则先验；全部在选手 API/离线算力内。
- **资源**：32 任务目标图（人工/半自动）；Gazebo-I 场景；1 张推理卡；N 端口部署。
- **风险**：意图误判 → 三重护栏（置信度门限、最大让行/重做时长、无进展则回退到 v2 的保守重做）。所有 `human_*` 先验必须标注为**离线设计知识**，评测时只能由观测推断。

## 2. 【附产物】人类干预意图分类表（从 v2 的 32 任务 `human_*` 语义整理）

**读表结论**：

1. **至少 11 个任务**含明确 `W/R`（v2 已标 ★），是“重做/恢复”的直接靶点。
2. 但**更多任务是 `D/O`**；它们不需要“重做”，而需要“重定位/让行”。v2 的单一 `regressed` 会在这些任务上产生假阳性。
3. `S` 是唯一可能**把人的动作变成助力**的类型（T05 双端插线）；识别出来可以少做一步。
4. `R` 与 `U` 的区分很重要：`R` 是“东西被拿走”，`U` 是“本来就没有/换成没见过的”。前者等待，后者接地。

## 3. 五个新模块

### 3.1 UIP-17 · CIA（Causal Intervention Attribution，因果干预归因）

**机制**：对每个块边界（必要时用时间堆叠的帧做块内近似），用前向模型 `f(o_t,A_t)` 预测“只有机器人动作时”的下一观测，计算残差 `r_{t+1}=o_{t+1}-f(o_t,A_t)`。然后：

```
P(c | o_t, A_t, o_{t+1}) ∝ P(o_{t+1} | c, o_t, A_t) · P(c | context)
c ∈ {robot, human, physics}
```

- `robot`：残差与指令方向一致，但目标未达成（抓空、滑脱、对不准）。
- `human`：残差**语义结构化**——物体回到完成前状态（`W`）、整体平移（`D`）、人手占用（`O`）、新物体出现（`S`）、物体消失（`R`）。
- `physics`：非指令方向的漂移、掉落、滚动；与人的进入无时间关联。

**实现选项（按合规风险从低到高）**：

1. **规则/几何优先**：物体跟踪 + 关系谓词 + 残差方向；零额外模型，最稳。
2. **共享骨干小头**：从主 VLA 的视觉特征蒸馏一个 3 类归因头 + 5 类意图头；仍是一条骨干。
3. **外部检测器**：人手检测/分割。**默认不用**；若用，必须先书面确认“单模型/外部模型”规则，并准备规则回退。

**关键**：归因的输出不是标签，而是**后验 + 置信度**；低置信度时默认“保守继续/观察”，不触发重做。

### 3.2 UIP-16 · HIFF（Human Intervention Forecasting，人类干预预测）

**机制**：估计进度条件风险率

```
λ_h(g,t) = lim_{Δt→0} P(在 [t,t+Δt) 内发生 h 型干预，目标为 g | X(t), b_t, ρ_t)
```

其中 `ρ_t` 是人手/人臂到工作区的视觉距离、机器人当前子目标、最近一次干预历史等。实现可以是：

- **规则先验**：从 `human_*` 文本得到每个任务的“易被干预步”与“干预类型”；例如 T19 拉链：`W` 在“拉上后”风险最高；T26 插网线：`O` 在“对准插口时”风险最高。
- **生存模型**：`λ_h(g,t)=λ_{h,g}^0 · exp(β^T φ_t)`，在线用观测更新；小数据下比深模型稳。
- **学习式风险头**：共享骨干上的一个小型时序头，输出离散时间 hazard；用 Gazebo-I/真机日志训练。

**用途**：

1. **调度**：高 `λ` 的高权重步尽量靠近终局完成（提高 `d_g`），但要留足时间；低权重步可先做“探针”。
2. **护栏**：`λ` 高时，块尾自动加“退让/保持”动作，降低块内盲区的承诺。
3. **解释**：把“为什么让行/为什么重做”变成可审计的 hazard 变化，便于调试。

**风险**：预测过早→机器人一直让行、任务做不完。必须设**最大让行预算**与“无进展超时回退”。

### 3.3 UIP-20 · ISC（Intervention-Safe Chunk，交互安全动作块）

**背景（对 v2 的纠偏）**：`action_chunk_size=T_a` 固定，动作数组形状必须严格 `(T_a,…)`；评测端整块执行后才重看。**运行期不能改 `T_a`，也不能返回短块。** v2 的 UIP-13“按阶段选 k、返回 ≤k”不成立。

**机制**：把 `T_a` 的选择放到**握手前的一次性离线决策**，把交互安全放到**块内容**：

- **全局 `T_a` 选择**：在验证集上扫 `T_a∈{1,2,4,8,16}`，用“成功率 + 步骤分 + 延迟方差 + 块内干预损失”选一个；接触密集任务多、人干预频繁 → 偏小；远距离搬运多 → 偏大。由于一个提交只能有一个 `T_a`，用**任务分布加权**选，而不是逐任务选。
- **低承诺块（low-commitment chunk）**：把每个块设计成“**可恢复的终点**”：
  - 块尾回到安全位（夹爪张开/手臂收回/不把物体悬在边缘）；
  - 插入/折叠/拉链等不可逆动作，拆成“接近块”（终点在接触前）与“接触块”（终点在接触后）；
  - 若 `HIFF` 风险高，块尾加入“护栏尾巴”：保持当前位姿/轻微后退，等待下一次观测。
- **承诺代价**：定义
  ```
  C(A_t) = E_{h~b_t}[ 块内发生干预时，因 A_t 已执行而造成的不可逆损失 + 安全风险 ]
  ```
  在“推进进度”和“降低 `C`”之间做贪心/滚动优化；`T_a` 固定，所以优化的是**块内动作序列的形状**。
- **不要做的**：块内“假装”返回短块、用零动作填充但不改形状（形状仍是对的就可行，但零动作可能被统计规律性判异常；需谨慎平滑）。

**与 UIP-13 的关系**：UIP-13 封存；其“按阶段调反应性”的合理内核被保留为“`T_a` 离线选择 + 块内阶段化模板”，但不再声称运行期可变块长。

### 3.4 UIP-18 · SHY（Safe Human Yield，安全让行包络）

**机制**：只用可用观测（四路 RGB + 本体），不做力控声明。

1. **视觉占用场**：从图像中检测人手/人臂/道具手（规则颜色/运动 + 共享骨干小头），投影到桌面工作区的 2D/2.5D 占用图；结合机器人末端位姿，估计“碰撞锥”。
2. **安全投影**：把策略输出 `A_t` 投影到安全集：
   - 降低朝向人的速度分量；
   - 若碰撞锥内有占用，改为**让行轨迹**（弧线绕开/后退/保持）；
   - 若无法安全通过，返回“保持”块（`T_a` 步小幅度保持/回撤），等下一次观测。
3. **恢复**：人离开后，用 `HIFF` 判断风险回落，再恢复原子目标；恢复前先做一次**视觉复核**（防止人又回来）。
4. **可读性**：接近/抓取/放置前减速与对准，避免突然反向；这同时降低“动作统计异常”的可信度风险。

**边界**：没有力/触觉，不能承诺“柔顺接触”；没有深度，距离是估计值，所以安全阈值取保守值，并在 Gazebo-I 中做压力测试。

### 3.5 UIP-19 · LIG（Language Intent Grounding，语言意图接地）

**机制**：把 `observation.language` 解析为类型化目标图 `G=(V,E,Φ)`：

- **任务库路由**：32 任务是公开的，用语言嵌入/关键词路由到任务模板（任务名、计分步、常见干预类型作为**先验**）。
- **属性化对象接地**：`V` 中对象用属性（颜色、形状、类别、可抓部位）描述；用视觉检测/分割把未见实例匹配到角色，而不是匹配到固定实例。
- **关系与顺序**：`E` 从任务模板 + 计分点顺序初始化；执行中由 `CIA` 更新（例如 `D` 位移后更新目标位姿，`S` 补料后增加节点）。
- **歧义处理**：语言含糊时，不做“问人”（无通道），而是选择**认知性动作**：移动到能同时看到多个候选的视角、暂停一个块观察、或先用低成本探针动作消除歧义。
- **合规**：优先模板/规则 + 共享语言编码器；外部 LLM 解析默认不用，除非书面确认允许。

**与 UIP-05 的关系**：UIP-05 的“语言→可供性/关系分解”并入此模块；不再单独维护两套语言前端。

### 3.6 UIP-09″ · HIIR（Human-Intent-aware Intervention Recovery）

v2 的 DCR-R 状态机升级为：

```
DETECT ──► ATTRIBUTE ──► CLASSIFY ──► WAIT_CLEAR ──► RESPOND ──► VERIFY
  │            │              │             │             │
  │            │              │             │             ├─ W: redo subgoal
  │            │              │             │             ├─ D: relocalize, continue
  │            │              │             │             ├─ O: yield, resume later
  │            │              │             │             ├─ S: integrate, replan
  │            │              │             │             └─ R: wait/return or give up step
  │            │              │             └─ 人手仍在工作区 → 保持安全位
  │            │              └─ 置信度低 → 观察一个块，不重做
  │            └─ robot/physics → 小步重试/重规划，不触发“人扰”分支
  └─ 无残差 → 继续
```

**硬护栏**：最大重做次数、最大让行时间、无进展超时、动作平滑；任何一项触发就回退到“保前置 + 保守继续”，避免死循环。

## 4. Gazebo-I / DRF-I：把“人的意图”变成可训练、可评测的变量

### UIP-11 · GSO-I（Gazebo Step-Score Oracle with Interaction）

- 在 v2 的 GSO 场景中加入**人类代理**（脚本化手/臂或道具手），其状态进入仿真观测；计分谓词仍判 32 任务步骤分，同时记录：
  - 干预类型 `h`、干预时刻、目标子目标 `g`；
  - 机器人是否碰撞/进入人手占用区；
  - 块内干预是否发生在“不可见窗口”。
- 用途：给 UIP-17/16 提供**带标签的归因与风险数据**；给 UIP-20 提供“块内干预损失”的离线评估。
- **边界**：仿真人手 ≠ 真人；只当**结构/时机代理**，不当视觉/接触成败代理（延续 v2 的 H4）。

### UIP-12 · DRF-I（Disturb-and-Recover data Factory with Intent labels）

- 按 §2 的分类，为每个任务生成：
  ```
  (干预前状态 o_t, 干预类型 h, 干预后状态 o_{t+1}, 恢复动作/恢复后状态 o_{t+k})
  ```
- 随机化：类型、时机（块内/块间）、速度、轨迹、是否拿走、是否补料；同一任务生成多种 `h`。
- 用途：训练/蒸馏 `CIA` 归因头、`HIIR` 响应策略、`HIFF` 风险头；也可做**反事实增强**（“如果人没动，会怎样”）。
- **合规**：合成数据要打标签、可追溯；是否允许用于训练需书面确认。

## 5. 关键算法伪代码

```python
class IntentAwarePolicy:
    """UIP-01″ = LIG + CIA + HIFF + SSG + ISC + SHY + HIIR."""

    def __init__(self, backbone, goal_lib, T_a, conf_thr=0.6,
                 max_redo=2, max_yield_ms=1500, safe_dist=0.12):
        self.backbone = backbone
        self.goal_lib = goal_lib          # 32 任务目标图 + 计分步先验
        self.T_a = T_a                    # 握手前选定，运行期不变
        self.conf_thr = conf_thr
        self.max_redo = max_redo
        self.max_yield_ms = max_yield_ms
        self.safe_dist = safe_dist

    def reset(self):
        self.backbone.reset()
        self.G = None                     # 目标图
        self.g = 0                        # 当前子目标
        self.b = {h: 0.0 for h in ("none","W","D","O","S","R")}
        self.b["none"] = 1.0
        self.redo = 0
        self.yield_ms = 0
        self.last_progress_t = 0
        self.history = []

    def get_action(self, obs):
        # 1) 任务意图：只在首帧/语言变化时解析
        if self.G is None:
            self.G = self.goal_lib.route(obs["observation.language"], obs)

        # 2) 因果归因 + 人的意图后验（块边界）
        cause, h, conf = self.attribute(obs)
        self.update_belief(cause, h, conf)

        # 3) 进度核验（是否需要重做/前进/让行）
        mode = self.decide_mode(obs, cause, h, conf)

        # 4) 选子目标（耐久性调度；小 G 可枚举）
        if mode in ("proceed", "redo", "replan"):
            self.g = self.schedule(obs)

        # 5) 生成固定 T_a 的低承诺块 + 安全投影
        A = self.make_chunk(obs, self.g, mode)
        A = self.safety_project(A, obs)
        return A

    def attribute(self, obs):
        # 规则/小头：残差 + 语义模板
        r = self.forward_residual(obs)
        if self.is_noise(r):
            return "robot", "none", 0.9
        if self.matches_withdraw(obs):
            return "human", "W", self.conf(obs, "W")
        if self.matches_displace(obs):
            return "human", "D", self.conf(obs, "D")
        if self.human_in_workspace(obs):
            return "human", "O", self.conf(obs, "O")
        if self.new_object(obs):
            return "human", "S", self.conf(obs, "S")
        if self.object_gone(obs):
            return "human", "R", self.conf(obs, "R")
        return "physics", "none", 0.5

    def decide_mode(self, obs, cause, h, conf):
        if conf < self.conf_thr:
            return "guard"                  # 低置信度：观察，不重做
        if cause == "human":
            if h in ("W",):
                if self.redo < self.max_redo:
                    self.redo += 1
                    return "redo"
                return "guard"
            if h in ("D",):
                return "replan"             # 重定位后继续
            if h in ("O",):
                return "yield"
            if h in ("S",):
                return "replan"             # 整合新物体
            if h in ("R",):
                return "wait"
        if cause == "robot":
            return "retry" if self.redo < self.max_redo else "guard"
        return "proceed"

    def schedule(self, obs):
        # 枚举合法拓扑序，最大化 Σ w_g * reach * durability
        # G<=5，离线预计算表；在线只查表 + 用 b(h) 修正 λ
        return self.durability_dp(self.G, self.b)

    def make_chunk(self, obs, g, mode):
        # 固定 T_a；块内容按模式模板化
        if mode == "yield":
            return self.hold_chunk(obs, retreat=True)
        if mode == "guard":
            return self.hold_chunk(obs, retreat=False)
        if mode == "wait":
            return self.hold_chunk(obs, retreat=True)
        # 接近/接触分块；若 HIFF 风险高，尾部加护栏
        risk = self.forecast(obs, g)
        head = self.backbone.act(obs, g, steps=self.T_a)
        if risk > 0.5:
            head = self.guard_tail(head, k=max(1, self.T_a // 4))
        return head[: self.T_a]

    def safety_project(self, A, obs):
        # 视觉占用 + 碰撞锥；必要时减速/绕行/保持
        return self.shy.filter(A, obs, safe_dist=self.safe_dist)
```

```python
# 耐久性调度的核心（小 G 可精确枚举）
def durability_dp(G, weights, hazard, budget):
    best = None
    for order in topological_orders(G):
        t = 0.0
        val = 0.0
        for g in order:
            t += G.duration[g]
            if t > budget:
                break
            d = exp(-hazard.integral(g, t, budget))
            val += weights[g] * d
        if best is None or val > best.val:
            best = (order, val)
    return best.order
```

## 7. 合规、风险与纠偏

- **单模型未核实**：README 未写；先按“可单模型化”设计（共享骨干 + 小头/规则），但不要为一个可能不存在的限制牺牲全部性能。外部人手检测器/LLM 默认不用，除非书面确认。
- **固定 `T_a`**：UIP-13 已封存；任何“运行期返回短块”的方案都会被 `example_env.py` 拒绝（形状必须 `(T_a,…)`）。UIP-20 只改块内容，不改形状。
- **无人类状态/力觉**：SHY 只能做视觉/本体安全投影，不能宣称力控柔顺；安全阈值保守，Gazebo-I 压力测试。
- **隐私与伦理**：人出现在相机里；不采集身份/面部特征，不做与任务无关的识别；合成数据打标签、可追溯；不伪造结果、不挑任务汇报。
- **仿真过拟合**：GSO-I/DRF-I 只训练“结构/时机”，必须用真机锚点校准（E210）；不能把仿真 `human_*` 当真人分布。
- **手册仍不可读**：5 轴中的位置/干扰物/背景、评测轮次/时限/控制频率仍待官方手册；本轮结论中凡涉及这些的一律标“待核实”。
