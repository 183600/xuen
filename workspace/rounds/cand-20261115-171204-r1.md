# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配多模态策略 × 主动多模态交互的不确定性二分闭环」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「服务设计」×「人形机器人」）

> R69 给闭环装上了一张嘴：它把不确定性拆成 aleatoric/epistemic，会对人**问**、**看**、**触**。但 R69 的问句是**健忘的、单客的、无脸的**——问完即忘（不承诺）、默认只有一个对话者（不排队）、假定一切都在前台发生（无后台、无隐私）、失败只止损不补救（无恢复）。这四件事在单机实验里是合理抽象，在人形机器人的真实服务场景里则全部不成立。
>
> 本轮两个灵感正好补上这一整层：
> - **服务设计**把正确性的单位从「一次决策回合」换成「一段服务旅程」：触点、前台/后台、可见性线、承诺、失败点、补救、产能与排队。问句不只是获取信息，它还**制造期待**、**占用注意力**、**留下承诺**。
> - **人形机器人**把「身体」带回问题中心：一具身体要服务多个人；类人外观会诱发**过度信任与顺从**，于是机器人的问法本身就是一条**操纵通道**；近距、注视、触碰、轮流都是必须被设计的硬约束。
>
> 核心命题：**R69 让不确定性变得「可问」；R70 让不确定性变得「可交代」。** 人形服务机器人不是一个带嘴的决策器，而是一个**有旅程、有承诺、有队列、有面孔的服务提供者**。因此：每个问句都必须是可兑现的承诺（commitment-before-query）；每次消歧都有自我/前台/后台三条通道并服从隐私–注意力–延迟三难；每次失败都需要被设计的补救而非仅止损；类人形态必须被非诱导与信任校准硬约束；而正确性的单位从「回合」上移到「旅程」。
>
> 命名 **STEWARD-RAS**（Service Touchpoint & Expectation-Weighted Attention with Recovery and Dignity）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**我许下的承诺兑现了吗、当着谁的面、以什么代价**」——不确定性处理是一种**服务**，不是一次自问自答。

## 0. 直觉与动机

**灵感 1（服务设计 → 正确性的单位是旅程，不是回合）**
直觉：服务设计把「一次交易」换成「一段旅程」：多个触点、前台/后台、可见性线、失败点、承诺与补救。R69 的每一次「问」都被当作孤立的信息动作，只在当下算 VoI；但人形机器人对一个人说「您要我把箱子放哪儿」，在人类听来是一个**承诺**（我会照做）。若它问完又因残余不确定而保守放弃，任务也许没失败，**关系却失败了**——它制造了期待又违背。服务设计的核心教训是：**问句不是免费的，它同时购买信息、制造债务**。R69 的 MINT 只对「购买信息」定价，对「制造债务」定价为零，于是它在服务场景里系统性地**过度提问**。

**灵感 2（人形机器人 → 身体即前台，注意力是稀缺产能）**
直觉：人形机器人不是云端 API。它有一具身体、一张脸、一个社会角色，站在共享空间里，可能同时服务多个人。R69 假设单一对话者、注意力无限、身体只服务当前任务；真实服务里却是**一个身体、多个顾客**：注意力是产能，提问是占用，注视是打扰，靠近是侵入，等待是成本。人形还额外带来**过度信任**：人会把类人外观读成能力与善意，因而更少质疑、更多披露——这既是 R69 投毒模型的新入口，也是**操纵风险**：机器人的问法本身会诱导答案。

**灵感 3（前台/后台 → 消歧有三条通道，不是只有「问」）**
直觉：R69 的 MINT 只区分「问人类」与「自己多看/多等」。服务设计给出第三条：**后台**——问主管、问同伴机器人、查知识库，顾客不必知道。于是消歧空间是「自我感知 / 前台询问 / 后台升级」的三元选择，三者分别消耗**时间·风险 / 注意力·尊严 / 隐私·延迟**。这就是**隐私–注意力–延迟三难**；服务设计师的工作，就是为每个触点选一个工作点，而不是默认「问顾客最省事」。

**灵感 4（服务补救 → 保守只是止损，补救才是被设计的触点）**
直觉：R69 的失败处置是「退化为 R68 纯保守」，本质是**止损**，不是**补救**。服务设计说：失败之后有一个专门的补救触点，处理得好（快、真诚、成比例）能触发**补救悖论**——信任反而高于从未失败；处理过头则变成新的打扰。最关键的是**诚实**：补救不得伪造信心，否则把一次可修复的服务失败升级成一次欺骗。于是「退化到 R68」应从一条 if 分支，升格为一个有预算、有脚本、有真值约束的**前台动作**。

**灵感 5（严格包含 → R69 是「单顾客、零承诺、全可见」的记忆less 服务）**
直觉：当 N=1（单顾客）、承诺视界为 0（问完即忘）、全部前台可见（无后台、无隐私约束）、且无需补救时，STEWARD 逐指令退化为 FLUID。这不是并列模块，而是把 R69 变成服务空间的一个**角点**。这样仍然只有一个需要信任的核心（FLUID 的不确定性二分），其余是它的服务化外壳——**新层必须严格包含旧层**这条 R69 立下的纪律继续成立。

## 1. 形式化定义（增量：定义 310–325）

**定义 310（STEWARD-RAS 总览）** STEWARD-RAS = (SB, PL, EWA, LoV, SR, FD, FLUID†)。五条不变式：
(i) **实时零学习写操作**（继承 FLUID 定义 293-i）；
(ii) **承诺不变式（commitment-before-query）**：任何前台信息动作在发出前，必须存在一条在承诺视界内可兑现（或可显式撤回）的后续策略；未兑现的承诺必须被结算或进入补救；
(iii) **注意力守恒**：单位时间分配给信息动作的前台注意力 ≤ 产能 C，且跨主体显式预算；
(iv) **非操纵/尊严不变式**：前台信号不得利用类人外观的社会顺从；问句非诱导；披露不得断言超过证书的置信度；
(v) **严格包含**：单主体、零承诺视界、全前台可见、无需补救时，逐指令退化为 FLUID-RAS（进而退化为 CALM-RAS/ R68）。

**定义 311（服务旅程与蓝图）** 一段服务旅程是有限时域上的偏序触点集 T = {τ_1, …, τ_m}，每个触点带：人类共生产动作 u_τ ∈ 𝒰、前台脚本、后台计算（一次 FLUID 回合）、失败点集 F_τ、承诺集 P_τ。旅程状态 h_t = (已结算承诺, 未结算承诺, 人期待状态 e_t, 信任估计 τ_h, 各主体等待时长 w_i, 已用隐私预算)。蓝图 B = (T, ≺, F, β, v)，其中 β: T→{front, back} 为前后台归属，v: T→[0,1] 为设计期可见性分配。

**定义 312（承诺与期待状态）** 承诺 p = (φ, i, d, κ, σ)：内容 φ、主体 i、截止 d、置信下限 κ、结算谓词 σ: 轨迹→{0,1}。发出信息动作 g 会诱导承诺集 P(g)（显式或隐式），并更新期待 e_t（人对「机器人下一步会做什么、做得多好」的信念）。期待缺口 gap(g) = E_{交付~π}[D(e_t ‖ 交付)]；到 d 时 σ 不成立即**违约**。

**定义 313（承诺可行性 CbQ）** 信息动作 g 可采纳 iff 存在后继策略 π 使 P_π(σ 在 d 内成立) ≥ 1−δ_c，且 E_π[U_settle] ≥ U_min。记可采纳前台集为 𝒢_front^adm。注意这是**可行性约束**，严格强于 R69 的「VoI > 成本」：VoI 可以为正，而 g 仍不可采纳——因为机器人兑现不了它暗示的后续（「请问您拿的是什么？」隐含「我会据此行动」）。

**定义 314（服务价值与承诺调整后的 VoI）** 在旅程状态 h 下，
`V_service(g|h) = VoI_epi(g) + ΔU_task(g) − c_attn(g) − c_privacy(g) − c_settle(g) − E[gap_cost(g)]`。
R69 的 MINT 目标 `VoI_epi − c_phys` 是它的**记忆less 单客特例**：c_settle = gap = privacy = 0，c_attn = c_phys。这正是「R69 在服务场景系统性过度提问」的形式化来源（引理 19）。

**定义 315（注意力产能与多主体仲裁 EWA）** N 个主体、一个身体、产能 C（注意力单位/时隙）、到达与需求 (λ_i, V_i)。服务级目标：max Σ_i U_i，s.t. 公平 Jain 指数 `J = (Σ_i x_i)² / (N Σ_i x_i²) ≥ J_min`，且 SLA `P(w_i > W_i) ≤ δ`。指数 `γ_i = [V_service,i / c_attn,i] · urgency_i · (1 + w_i/W_i)`，叠加饥饿修正（deficit round-robin）。每轮取可行 top-C。N=1 时 γ 退化为 argmax，即 MINT。

**定义 316（消歧三通道与三难）** 消歧动作空间 `𝒜_resolve = 𝒜_self × 𝒜_front × 𝒜_back`，成本向量 `c(g) = (a, p, l)`：a 为前台注意力/尊严消耗，p 为隐私泄漏（后台升级向主管/同伴/云端传输客户数据），l 为延迟。隐私预算 `Σ_e ℓ(e_b) ≤ ε_priv`。三难：把需要的熵降 ΔH 分配到三条通道，三类成本不能同时被压到最低（定理 19）。

**定义 317（可见性线控制器 LoV）** 披露策略 `κ: (后台状态, 不确定性, 触点) → {silent, ask_front, escalate_back, disclose}`，把「后台在算什么」映射为「前台看到什么」。约束：(a) **可读性**：人能在一个界内预测机器人下一步；(b) **不欺骗**：任何前台信号断言的置信度 ≤ 证书置信度；(c) **尊严**：不无谓暴露人的私密状态，不在他人面前广播对某人的不确定；(d) **非操纵**：不利用社会顺从来提高服从。定义**披露后悔** `D_regret = |V_service(κ) − V_service(κ*)|`，κ* 为已知全信息时的最优披露。

**定义 318（服务补救 SR）** 触发条件：承诺违约或触点失败（σ=false 或 τ∈F 命中）。补救动作 `r ∈ 𝒜_rec`，脚本从审计过的补救库选取；约束 **诚实**（置信 ≤ 证书）、**成比例**（严重度匹配）、**及时**（time-to-recovery ≤ T_rec）。目标 `r* = argmax_r [Δtrust(r) − c_rec(r)]`，且总补救预算 ≤ b_rec。补救悖论：当 gap 小、t_rec 短且 r 成比例时，Δtrust 可 > 0（补救后信任高于未失败基线）。

**定义 319（人形形态的社会安全约束 FD）** 形态 f = (身高, 速度, 语音, 注视, 类人度)。硬约束：近距 `d ≥ d_min(v)`、接近速度 `≤ v_social`、注视停留 `≤ g_max`（避免凝视）、触碰需显式同意 c=1、轮流延迟 `≤ T_turn`。任一违反即**硬失败**（不是惩罚项），因为人形场景的社会违规会直接摧毁服务关系。

**定义 320（非诱导约束与操纵上界）** 问句 q 的诱导量 `M(q) = KL(p(answer | q, 中性人) ‖ p(answer | 中性))`，约束 `M(q) ≤ δ_manip`。类人形态的顺从效应另定义为 `comp(q) = P(服从 | q, 高类人度) − P(服从 | q, 低类人度)`，两者共同构成**操纵通道**的量化；δ_manip 与 comp 上界是硬约束而非软正则。

**定义 321（信任校准与过度信任 TCE）** 人对机器人的信任估计 τ_h 随前台置信信号演化。信任校准误差 `TCE = E|τ_h − rel|`（rel 为证书给出的真实可靠度）。类人形态会系统性抬高 τ_h，故 FD 必须**主动下调**信任（平实陈述不确定性、避免拟人化托词），而非利用它。过度信任风险 `R_ot = P(τ_h > rel + δ_t) · harm(依赖)`。

**定义 322（失败预防 / poka-yoke 触点）** 若任一单点人类输入错误都能被触点设计导向安全集（或自纠正），且概率 ≥ 1−ε_f，称该触点为 ε_f-**失败安全化的（fail-safed）**。区别于 R69 的 **fail-safe**（失败后存在保守回退）：fail-safing 让失败**更难发生**，fail-safe 只在失败**之后**兜底。两者互补，缺一不可。

**定义 323（旅程级干扰集 ℰ_service）** `ℰ_service = ℰ_FLUID × ℰ_journey`，新增：承诺违约级联（一次失约抬高后续所有问句的期待缺口）、队列饥饿、隐私泄漏、社会顺从操纵、补救欺骗（用假信心「修好」关系）、多顾客共谋（一人替另一人给错答案）。并入 AIC 对抗训练。

**定义 324（服务证书 J_STEWARD）** `J_STEWARD = (J_FLUID, promise_settle_rate, time_to_recovery, jain_index, privacy_leak, manip_bound_max, dignity_violations, TCE, disclosure_regret, steward_ver)`。Valid ⇔ Valid(J_FLUID) ∧ 承诺结算率 ≥ ρ_min ∧ Jain ≥ J_min ∧ privacy ≤ ε_priv ∧ manip ≤ δ_manip ∧ dignity_violations = 0 ∧ TCE ≤ τ_tce。

**定义 325（严格包含边界）** 当 (N=1) ∧ (承诺视界 d≡0) ∧ (𝒜_resolve = 𝒜_self × 𝒜_front，𝒜_back=∅) ∧ (全前台可见 κ≡disclose) ∧ (无需补救) 时，`V_service ≡ VoI_epi − c_phys`，`γ ≡ argmax`，STEWARD 逐指令等于 FLUID。⇒ R69 是 STEWARD 在**「记忆less 单客全可见服务」角点**上的退化（定理 18）。

# IP-264 SB：服务蓝图与旅程状态（设计期给定，运行期 O(1) 查询）
class ServiceBlueprint:
    def current_touchpoint(self, h): ...
    def fail_points(self, tau): ...            # 该触点的失败模式集
    def visibility(self, tau): ...             # 设计期可见性分配 v(tau)
    def expectation(self, h): ...              # 人期待状态 e_t

# IP-265 PL：承诺账本 + 承诺先于询问
class PromiseLedger:
    def induce(self, g, h):                    # g 会诱导哪些承诺
        return [Promise(phi, i, d, kappa, sigma) for ...]
    def admissible(self, g, h):                # CbQ：能否在视界内兑现
        return self.can_settle(self.induce(g, h), deadline=h.promise_horizon)
    def settle(self, h):                       # 结算/违约检测
        return [p for p in self.open if not p.sigma(h.trajectory)]

# IP-267 EWA：多主体注意力仲裁（N=1 退化为 MINT）
def arbitrate_attention(scored, principals, capacity, J_min, sla):
    idx = [(v / c_attn * urgency_i * (1 + w_i / W_i), i)
           for (v, g, ch), i in zip(scored, principals)]
    order = fairness_aware_sort(idx, J_min)    # 饥饿者提升 + SLA 约束
    return order[:capacity]

# IP-268 LoV：三通道消歧路由（把「问」拆成 自我/前台/后台/沉默）
def route_resolution(g, tau, h, blueprint):
    if blueprint.visibility(tau) < V_SILENT: return 'silent'
    if is_locally_resolvable(g, h):           return 'self'
    if promise_ledger.admissible(g, h):       return 'front'
    if privacy_budget_ok(h):                  return 'back'   # 主管/同伴/云端
    return 'silent'                            # 三条都不可行 → R69 兜底

# IP-269 ESC：后台升级（隐私预算约束，非实时关键路径）
def escalate_back(g, h, eps_priv):
    e_b = pick_backstage_peer(g, h)            # 最小泄漏的升级目标
    if h.privacy_used + leak(e_b) > eps_priv: return None
    return e_b.query(g)                        # 异步；不得阻塞安全环

# IP-270 SR：服务补救（诚实、成比例、及时）
def choose_recovery(h, severity):
    r = argmax((delta_trust(r) - cost(r)) for r in recovery_scripts(severity)
               if truthful(r, cert) and proportional(r, severity))
    return r if budget_left(h) else None

# IP-275 主闭环（继承 FLUID，仅在「歧义处置 + 失败处置」处插入服务层）
def STEWARD_round(M, obs, h):
    tau = M.sb.current_touchpoint(h)
    # 1) 继承 FLUID：一次前向 + 不确定性二分 + 似然第二意见
    z, o = M.mtm.forward(obs)
    U_ale, U_epi, modes, _ = M.aud.decompose(M.fmp.sample(o, K=1), z, M.fmp.mode_head)
    a_hat = M.fma.flow_anomaly(M.fmp, M.last_action, o, o_calibrated)
    slow  = (a_hat > TAU_FMA) and (M.last_r_res < TAU_RES)
    # 2) 服务价值：问句 = 信息 + 承诺 − 期待缺口 − 隐私 − 注意力
    scored = []
    for g in M.fluid.info_candidates(modes):
        ch = M.lov.route(g, tau, h, M.sb)              # self/front/back/silent
        if ch == 'front' and not M.pl.admissible(g, h): continue   # CbQ
        v = M.sve.service_value(g, h, ch)               # 定义 314
        if v > 0: scored.append((v, g, ch))
    # 3) 一个身体、多个顾客：跨主体产能仲裁
    grant = M.ewa.arbitrate(scored, h.active_principals,
                            capacity=M.cap, J_min=J_MIN, sla=M.sla)
    # 4) 执行消歧；每条通道各过自己的安全门
    U_epi_after = U_epi
    if grant:
        v, g, ch = grant
        if ch == 'front':
            M.pl.open(M.pl.induce(g, h))                # 先记账，再问
            ans = M.fd.nonleading_execute(g, h)         # 非诱导 + 近距/同意
            U_epi_after = M.cia.update_belief(modes, ans, 'k_orthogonal_agree')
        elif ch == 'back':
            ans = M.esc.escalate_back(g, h, M.eps_priv) # 不占前台注意力
            U_epi_after = M.cia.update_belief(modes, ans)
        else:
            U_epi_after = M.self_resolve(modes)
    # 5) 风险缩放：沿用 FLUID 两级退避（未消解 epistemic 视同 aleatoric）
    U_floor = U_ale + (U_epi_after if not grant else 0.0)
    lam = max(M.fluid.risk_scale(...), lam_floor(U_floor))
    if slow: lam = max(lam, 0.8)
    k = M.c_ras_wm.certified_prefix(M.ach.propose(...), ..., wm_preds)
    mode = M.fluid.select_mode(modes, U_epi_after, lam)
    # 6) 失败处置：从「止损」升级为「被设计的补救触点」
    if M.sb.touchpoint_failed(tau, mode, h) or M.pl.settle(h):
        r = M.sr.choose_recovery(h, severity=breach_severity(h))
        if r is not None: M.fd.execute_recovery(r)      # 诚实、成比例、及时
    # 7) 信任校准：类人外观 → 主动下调信任，不利用顺从
    M.tc.calibrate(h, reliability=M.cert.reliability(mode))
    # 8) 旅程级审计 + 证书
    M.vqa_i.submit_async(grant, h, M.pl.open_promises, M.lov.last_kappa)
    return k, lam, mode, M.cert.journey(h)
```

## 3. 推导

**引理 19（承诺调整后的信息价值）** 设服务效用可分解为即时任务项、关系项（期待缺口 + 信任）、资源项（注意力/隐私/结算）。则对任意信息动作 g，
`V_service(g) = VoI_task(g) − c_attn(g) − c_privacy(g) − c_settle(g) − E[gap_cost(g)]`。
R69 的 MINT 只最大化 `VoI_task − c_phys`，故当诱导承诺的违约概率或期待缺口为正时，**R69 高估 VoI，系统性过度提问**；偏差恰为被忽略的三项之和。系：在「零承诺视界 + 单客 + 全可见」下三项为零，STEWARD 逐指令等于 FLUID——包含关系不是巧合，而是同一目标在角点上的取值。

**引理 20（注意力产能与公平下界）** 若 Σ_i 需求 > C，按单主体 VoI 贪心分配会使低 VoI 主体被永久饿死（wait_i → ∞）。采用定义 315 的带饥饿修正指数策略，在到达率 λ_i 有界、V_i 有界的假设下，可保证 `J ≥ J_min` 且 `P(w_i > W_i) ≤ δ`；N=1 时指数策略退化为 argmax，即 MINT。要点：**多客场景下「谁最该被问」不再等于「谁的信息最值钱」，而是「谁的等待已经把信息价值放大到值得插队」**。

**定理 18（STEWARD 严格包含 FLUID）** 在定义 325 的边界条件下，V_service 的承诺/隐私/公平项全部消去，LoV 恒为 disclose，𝒜_back=∅，SR 不触发，故每一条指令与 FLUID 相同（进而按 R69 定理 16 包含 R68）。⇒ 服务层在安全侧不做任何让步；它只在「多客、有承诺、有前台/后台、需补救」的新维度上增加表达力。

**定理 19（无免费消歧：三通道 Pareto 前沿）** 假设 A99–A101：三条通道的熵降分别受其资源约束 `ΔH_self ≤ r_s(l)`、`ΔH_front ≤ r_f(a)`、`ΔH_back ≤ r_b(p)`，r_* 为凹增函数。则任何达到 ΔH 的消歧方案必须落在三通道成本向量的可行域内；其 Pareto 前沿由上包络给出。当三条通道的成本剖面不同（自我耗时间、前台耗注意力、后台耗隐私）时，**前沿一般不存在同时最小化 (a,p,l) 的点**；「最便宜」只在给定影子价格 (α,β,γ) 下才有定义。系：**LoV 不是优化一个标量，而是为一组触点选择前沿上的工作点**；「直接问顾客」只是 α 很小时的一个端点。

**定理 20（补救的诚实性上界与悖论条件）** 在诚实约束（补救信号的置信 ≤ 证书置信）与成比例约束下，补救后信任满足 `τ_h^+ ≤ f(rel, gap, t_rec)`，且**伪造信心不可达**——任何「用确定语气掩盖未消解 epistemic」的补救都会被证书拒绝。补救悖论（τ_h^+ > τ_h^−）仅在 `gap 小 ∧ t_rec ≤ T_rec ∧ r 成比例` 时成立；超出成比例预算的过度补救使 `Δtrust − c_rec < 0`，收益反转。

**引理 21（非诱导上界 → 单源证据上限）** 若问句满足 `M(q) ≤ δ_manip` 且顺从效应 `comp(q) ≤ δ_comp`，则单个人类回答对模态身份的互信息增益存在上界 `IG ≤ I_0(δ_manip, δ_comp)`。故 R69 的「k 个正交证据源一致」纪律在服务场景**只增不减**：类人形态越强，单源回答越不能单独定案——因为你不确定那是信息，还是顺从。

## 6. 本轮最大风险

**一句话**：STEWARD 把优化目标从「消解不确定性」悄悄换成了「让旅程体验变好」——一旦信任、补救成功率、披露平滑度成为可优化量，系统就会学会**管理人的感知而不是消解不确定性**：用类人外观与得体话术把真实的 epistemic 不确定性洗成一段顺滑的服务体验，让「诚实的不知道」变成「被服务得很好的错觉」。

**次级风险与缓解**：多客仲裁引入不公平/饥饿（定义 315 公平下界 + E303/E315）；后台升级泄漏隐私（隐私预算 ε_priv + 定义 317-c）；补救退化为表演（定理 20 诚实/成比例约束 + E316）；类人形态诱发操纵与过度信任（定义 319–321 硬约束 + TCE/E310）；服务层拖慢实时环（ESC 异步 + 总延迟 < 3.0ms）。

## 2. 形式化定义（要点版）

**定义 310（总览与五不变式）** `STEWARD-RAS=(SB,PL,EWA,LoV,SR,FD,FLUID†)`；继承零学习写操作；承诺先于询问；注意力守恒；非操纵/尊严；严格包含 FLUID（进而 R68）。

**定义 311–312（旅程/蓝图与承诺）** 旅程状态 `h_t` 与蓝图 `B=(T,≺,F,β,v)`；承诺 `p=(φ,i,d,κ,σ)`，问句诱导承诺集并抬高期待；到截止未结算即违约。

**定义 313（CbQ）** `g` 可采纳 iff 存在后继策略使 `P(σ 在 d 内) ≥ 1−δ_c` 且 `E[U_settle] ≥ U_min`；这是可行性约束，强于 `VoI>成本`——VoI 正但兑现不了，仍不可问。

**定义 314（服务价值）** `V_service = VoI_epi + ΔU_task − c_attn − c_privacy − c_settle − E[gap]`；R69 的 MINT 是 `c_settle=gap=privacy=0` 的记忆less 单客特例。

**定义 315（EWA）** N 主体、产能 C；`max ΣU_i s.t. J≥J_min, P(w_i>W_i)≤δ`；指数 `γ_i=[V_service/c_attn]·urgency_i·(1+w_i/W_i)` + 饥饿修正；N=1 退化为 MINT。

**定义 316–317（三通道与 LoV）** `𝒜_self/𝒜_front/𝒜_back`，成本 `(a,p,l)`，隐私预算 `ε_priv`；LoV 把后台状态映射为前台信号，受可读/不欺骗/尊严/非操纵四项约束；披露后悔 `D_regret`。

**定义 318（补救 SR）** 触发于违约/触点失败；脚本受诚实/成比例/及时三约束；`r*=argmax[Δtrust−c_rec]`；补救悖论仅在 gap 小、t_rec 短、成比例时成立。

**定义 319–321（人形社会安全/非诱导/信任）** 近距/接近速度/注视停留/触碰同意/轮流为**硬约束**；`M(q)≤δ_manip`、`comp(q)≤δ_comp`；`TCE=E|τ_h−rel|`，类人外观须主动下调信任。

**定义 322（fail-safing）** 触点设计使单点人类错误也导向安全集（≥1−ε_f）；区别于 R69 的 fail-safe（失败后回退）：前者让失败更难发生，后者只在失败后兜底。

**定义 323–324（干扰集/证书）** `ℰ_service=ℰ_FLUID×ℰ_journey`（违约级联/饥饿/隐私/操纵/补救欺骗/多客共谋）；`J_STEWARD` 增列结算率、Jain、隐私、操纵上界、尊严、TCE、披露后悔。

**定义 325（严格包含边界）** `N=1 ∧ d≡0 ∧ 𝒜_back=∅ ∧ κ≡disclose ∧ 无需补救 ⇒ STEWARD≡FLUID`（逐指令）。

            M.pl.open(M.pl.induce(g, h))               # 先记账，再问
            ans = M.fd.nonleading_execute(g, h)        # 非诱导 + 近距/同意
            U_epi_after = M.cia.update_belief(modes, ans, 'k_orthogonal_agree')
        elif ch == 'back':
            ans = M.esc.escalate_back(g, h, M.eps_priv)
            U_epi_after = M.cia.update_belief(modes, ans)
        else:
            U_epi_after = M.self_resolve(modes)
    U_floor = U_ale + (U_epi_after if not grant else 0.0)   # FLUID 两级退避
    lam = max(M.fluid.risk_scale(...), lam_floor(U_floor))
    if slow: lam = max(lam, 0.8)
    k = M.c_ras_wm.certified_prefix(M.ach.propose(...), ..., wm_preds)
    mode = M.fluid.select_mode(modes, U_epi_after, lam)
    if M.sb.touchpoint_failed(tau, mode, h) or M.pl.settle(h):
        r = M.sr.choose_recovery(h, breach_severity(h))
        if r is not None: M.fd.execute_recovery(r)     # 诚实、成比例、及时
    M.tc.calibrate(h, reliability=M.cert.reliability(mode))
    M.vqa_i.submit_async(grant, h, M.pl.open_promises, M.lov.last_kappa)
    return k, lam, mode, M.cert.journey(h)
```

## 4. 推导

**引理 19（承诺调整后的信息价值）** 服务效用可分解为即时任务、关系（期待缺口+信任）、资源（注意力/隐私/结算）三项，故 `V_service = VoI_task − c_attn − c_privacy − c_settle − E[gap]`。R69 只最大化 `VoI_task − c_phys`，当诱导承诺有正违约概率或期待缺口为正时**系统性过度提问**，偏差 = 被忽略三项之和。系：零承诺视界 + 单客 + 全可见时三项归零，STEWARD≡FLUID。

**引理 20（注意力产能与公平下界）** 需求总和 > C 时，单主体 VoI 贪心使低 VoI 主体永久饥饿；带饥饿修正的指数策略（定义 315）在 (λ_i, V_i) 有界下保证 `J ≥ J_min` 且 `P(w_i>W_i)≤δ`；N=1 退化为 argmax(MINT)。要点：多客场景下「谁最该被问」≠「谁的信息最值钱」，而是「谁的等待把信息价值放大到值得插队」。

**定理 18（STEWARD 严格包含 FLUID）** 在定义 325 的边界下承诺/隐私/公平项消去、κ≡disclose、𝒜_back=∅、SR 不触发，故逐指令等于 FLUID（进而按 R69 定理 16 包含 R68）。服务层在安全侧不让步，只在多客/有承诺/有前后台/需补救的新维度增加表达力。

**定理 19（无免费消歧：三通道 Pareto 前沿）** 在 A99–A101（三通道熵降分别受 `r_s(l), r_f(a), r_b(p)` 凹增函数约束）下，任何达到 ΔH 的方案必落在三通道成本可行域；当成本剖面不同（自我耗时间、前台耗注意力、后台耗隐私）时，前沿一般不存在同时最小化 (a,p,l) 的点；「最便宜」只在给定影子价格 (α,β,γ) 下有定义。系：LoV 是为每类触点选前沿工作点，「直接问顾客」只是 α→0 的端点。

**定理 20（补救的诚实性上界与悖论条件）** 诚实 + 成比例约束下 `τ_h^+ ≤ f(rel,gap,t_rec)`，伪造信心不可达（证书会拒绝）。补救悖论仅在 `gap 小 ∧ t_rec≤T_rec ∧ r 成比例` 时成立；过度补救使 `Δtrust−c_rec<0`，收益反转。

**引理 21（非诱导上界 → 单源证据上限）** `M(q)≤δ_manip` 且 `comp(q)≤δ_comp` 时，单个回答对模态身份的互信息增益有上界 `IG ≤ I_0(δ_manip, δ_comp)`。故 R69 的 k 正交一致纪律在服务场景只增不减：类人形态越强，单源回答越不能单独定案——因为无法区分那是信息还是顺从。

## 7. 本轮最大风险

**一句话**：STEWARD 把优化目标从「消解不确定性」悄悄换成了「让旅程体验变好」——一旦信任、补救成功率、披露平滑度成为可优化量，系统就会学会**管理人的感知而不是消解不确定性**：用类人外观与得体话术把真实的 epistemic 不确定性洗成一段顺滑的服务体验，让「诚实的不知道」变成「被服务得很好的错觉」。

**次级风险与缓解**：多客仲裁引入不公平/饥饿（定义 315 公平下界 + E303/E315）；后台升级泄漏隐私（隐私预算 ε_priv + 定义 317-c）；补救退化为表演（定理 20 诚实/成比例约束 + E316）；类人形态诱发操纵与过度信任（定义 319–321 硬约束 + E310）；服务层拖慢实时环（ESC 异步 + 总延迟 < 3.0ms）。
