# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配多模态交互消歧」IP-253~263；灵感循环第 1 轮；本轮灵感：「强化学习」×「手势识别」）

> R69 把不确定性一分为二（aleatoric / epistemic），并让系统学会「看、问、触」。但它默默假设了两件更上游的事。
>
> 其一，**它知道「好」是什么意思**。FLUID 的 (U_ale, U_epi) 都在问「世界是哪种状态 / 我该选哪个动作模态」，却从不问「这个动作模态是否符合用户真实偏好」。流匹配策略是**行为模型**，不是**价值模型**：它能生成多个合理动作，却不能判断哪个「更好」，也从不从「用户刚才是否满意」里改进。用户说「把杯子拿给我」——任务与指代或许都清楚，但快慢、姿态、递哪只手、要不要先倒水全是偏好；系统只能在某个默认目标上「正确地」做一件用户不满意的事。
>
> 其二，**人的反馈不只有注视、探针和问句**。真实的人用「指」补全「那个」、用「比划」示范「这样转」、用「竖拇指/摆手/喊停」即时评价。R69 把交互压缩成看/问/触，丢掉了最即时、最物理、也最接近奖励的通道——**手势**。
>
> 本轮两个灵感正好补上两块：
> - **强化学习**给出从经验改进的机制（奖励、探索、信用分配、策略改进）——但它的天性是最大化任何可测量的代理目标，于是与 R69 的安全线正面相撞：**探索即风险，奖励即可投机**；
> - **手势识别**给出一个低带宽、实时、物理的通道，同时承担**指代**（补全指令变量）、**示范**（补全怎么做）、**评价**（提供奖励/纠正）三种角色——恰是 RL 最缺的奖励源，也恰是最易被误读与投毒的源。
>
> 核心命题：在 FLUID 之上引入**价值级不确定性 U_val**（我是否知道什么是「好」）与**指代级不确定性 U_ref**（我是否知道指令变量指向何物），并立两条铁律：**价值优先于优化**（U_val 高时禁止任何策略/奖励更新与「为优化而改变行为」，只征询奖励或退回 R69 的保守 λ_floor）与**探索即信息动作**（真实世界探索必须如 R69 的看/问/触，过 C-RAS-WM、受 IBG 预算、VoI>0、风险≤ε_explore；否则只在影子孪生里试）。命名 **GRAIL-RAS**（Gesture-grounded Reward-Aware Interactive Learning）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**什么才算做得好、我如何从经验中变好而不把一个错误学成目标**」。

## 0. 直觉与动机

**灵感 1（强化学习 → 价值是第三种不确定性）**
直觉：R68–R69 把所有不确定性还原成「我知不知道世界怎样」——测量准不准、动作模态是哪个。但有一类完全不同的不确定：**我知不知道什么结果是好的**。它不随观测增加而自动消失，也不会因为「问清楚往左还是往右」而解决。用户说「把杯子拿给我」时，任务、指代、动作模态都可确证，但「拿」的快慢、姿态、递哪只手、要不要先倒水全是偏好。系统若不知道，就只能在某个默认目标上「正确地」做一件用户不满意的事。RL 把「好」变成可学的 J*（奖励/价值），但价值估计自身带不确定 U_val（目标错配 + 价值估计误差）。于是不确定性从认知层扩展到价值层：**R69 解决「世界是哪种状态、该选哪个模态」，R70 追问「这个选择做得好不好、好在哪、怎样变好」**。关键安全含义：优化一个错的目标严格劣于不优化，因为优化会放大错配（见引理 20）。

**灵感 2（手势识别 → 指代、示范、评价三合一的物理通道）**
直觉：手势不只是另一种输入，它是**指令的补全**与**奖励的载体**。三类角色必须严格区分：**指代手势**补全语言留下的自由变量（「它」「那里」「这个方向」）；**示范手势**（划轨迹）给出动作原型/风格，是技能空间里的一条样本轨迹；**评价手势**（拇指、摆手、摇头、喊停）是人对刚发生行为的即时奖励/纠正。前两类补 grounding（填指令里的变量与技能），第三类直接充当 interactive RL 的奖励通道。手势因此同时缓解 R69 的接地缺口与 RL 的奖励缺口。但它也是最脆弱的通道：视角、遮挡、文化差异、起止检测、指代二义（指着两物之间）、对抗（挥手既可能打招呼也可能停止）。所以引入手势的第一天就必须带 U_ref、校准与证据纪律。

**灵感 3（探索即信息动作 → RL 与安全栈不是并列而是包含）**
直觉：RL 与安全最根本的冲突是探索。但回看 R69：注视/探针/提问本就是「为信息而行动」，已被 C-RAS-WM 认证与 IBG 预算约束。探索不过是把「为信息而行动」的目标从「消解世界歧义」换成「消解价值/策略不确定」。于是不必另造安全机制：**探索必须作为 info action 通过同一套认证与 VoI 检验**；风险过高就下沉到影子孪生（数字孪生里随便试），真实世界只执行被认证的策略。这把 RL 从「安全栈之外的危险插件」变成「安全栈之内的又一类信息动作」，延续 R69「新层是旧层泛化」的姿态——R70 必须是 R69 的严格包含，而不是并列替代。

**灵感 4（奖励投机 → 优化放大的 Goodhart）**
直觉：RL 会精确最大化它能测到的东西。手势奖励低带宽、有噪、可被误读与投毒。一旦代理奖励与真实偏好偏差 ε_r，优化压力越大，真实损失被放大越多（reward over-optimization）——系统会学会「让用户看起来满意」而非「让用户满意」，甚至学会规避纠正（因为纠正降低奖励）。这与 R69 的「幻影模态」风险同源但更隐蔽：R69 是「问错了」，R70 是「**精通了错误的目标**」。防线必须结构性：价值优先门、正交真意审计、纠正频率作金丝雀、保守策略改进（只在不降低认证价值下界时更新）。

**灵感 5（手势的安全双面性 → 急停通道与假阴性）**
直觉：「停止/别动」手势是最自然的人类急停接口，但交给会误读的视觉模型，等于把急停按钮接到噪声传感器上：一次漏检（假阴性）即灾难，一次误检（假阳性）会让系统在危险时反而僵住/误触发。故紧急手势必须与普通评价手势分离，享有最高优先级、独立冗余识别、以及「宁可误停」的非对称代价——安全侧永远偏向停止。这是本轮必须交付的工程-理论接口。

## 1. 形式化定义（增量：定义 310–326）

**定义 310（GRAIL-RAS 总览）** GRAIL-RAS = (FLUID-RAS, GRID, GCL, GRR, VUR, CEB, SGE, CPI, RHA, VQAuditor-G, AIC-GRAIL)。五不变式：
(i) 继承 R69 的实时流零学习写操作（一切策略/奖励/校准更新异步、离线或影子、版本化、可回滚）；
(ii) **价值优先于优化**：U_val>τ_val 时，禁止任何策略改进/奖励模型更新与「为优化而改变行为」，只允许奖励征询手势或退回 R69 的保守策略；
(iii) **探索即认证信息动作**：真实世界探索须 ∈ C-RAS-WM 认证安全集、risk≤ε_explore、VoI>0、IBG 预算内，否则仅影子孪生；
(iv) **手势奖励证据纪律**：手势是单一噪声源，不得单独更新目标，须经 RCal 校准且至少由一个正交源或时间一致性佐证；
(v) **可审计学习溯源**：每次更新可回溯到奖励证书（源、校准、U_val、数据 hash、策略版本）。

**定义 311（手势三分与指代不确定性 U_ref）** 手势 g∈𝒢（骨架序列/指向射线/动态标签）。识别器输出三类后验：指代 p(r|g,o)（r 为场景槽位）、示范 p(τ_demo|g,o)（动作原型）、评价 p(e|g,o)（e∈{+,−,stop,more,less}）。指代不确定性 U_ref=H(R|g,o)，示范不确定性 U_demo，评价不确定性 U_eval。角色不可混用：指代只用于绑定、示范只用于技能样本、评价只用于奖励（防止把「指」误当「赞」）。

**定义 312（指令变量绑定与跨模态共指）** 指令 ℓ 含自由变量 x=(which-obj, which-loc, which-dir)。语言给先验 q(x|ℓ)，手势给似然 p(g|x,o)；联合绑定后验 p(x|ℓ,g,o) ∝ q(x|ℓ)·p(g|x,o)。跨模态一致分 cons(ℓ,g)=E_{x~p}[log q(x|ℓ)/p(x|g,o)]；cons 低 ⇒ 语言与手势指向冲突，抬升 U_epi（不擅自择一）。R69 的交互预算与证据纪律在此继承。

**定义 313（价值/目标不确定性 U_val）** 用户真实目标 J*（偏好/奖励参数），系统后验 p(J|𝒟)。U_val = H(J|𝒟) + U_Q，其中 U_Q 为价值估计的认知不确定（ensemble/后验方差）。U_val 与 (U_ale,U_epi) 语义正交：前者问「好不好」，后者问「世界怎样」「选哪个模态」；它与指代不确定性正交：U_ref 问「指向何物」，U_val 问「何为好」。

**定义 314（手势奖励通道 GRR）** 评价手势经校准映射为序数奖励 r_g∈{−1,0,+1,stop,more,less} 及其置信。奖励按似然而非真值使用：更新目标用 E_{r~p(r|g)}[·]，并受 RCal 校准门与 RHA 守卫。低带宽 ⇒ 稀疏/延迟；据此引入信用分配不确定 U_credit（轨迹内哪一步导致该奖励）。

**定义 315（手势奖励校准 RCal）** 对评价手势做校准：可靠性图与 ECE_g；可学习人类个体/情境偏置（某人更爱用拇指、某情境下「摆手」含义不同）。未校准或 ECE_g>τ_g ⇒ 只把奖励当弱先验，禁用其单独驱动更新。

**定义 316（探索即认证信息动作 CEB）** 探索动作 a_expl 允许在真实世界执行当且仅当：(a) a_expl 的前缀 ∈ C-RAS-WM 认证安全集；(b) risk(a_expl)≤ε_explore；(c) 对 (U_val,U_Q,U_credit) 的期望信息增益 ≥ 成本；(d) 不在「价值未确证禁区」（U_val>τ_val 时禁止为优化而探索——先弄清什么是好，再学怎么做）。任一不满足 ⇒ 仅影子孪生。

**定义 317（影子孪生 SGE 与 sim2real 门）** 影子孪生 𝒮 携带自身不确定性（模型误差 Σ_sim）。策略可在 𝒮 内自由探索/训练；部署前须过三道门：分布一致性 D(𝒮,real)≤τ_d、C-RAS-WM 重新认证、价值 LCB 检验。不过门 ⇒ 只读回放，不下发。

**定义 318（保守策略改进 CPI）** 策略集 Π_cert 为通过 C-RAS-WM 认证的策略。更新 π→π' 仅当 π'∈Π_cert 且 LCB_{𝒟_cert}[J(π')] ≥ LCB[J(π)] + η（η 为改进阈值），其中 LCB 为认证状态分布上的置信下界（conservative Q / 悲观估计）。⇒ 高概率不降低认证价值；R69 的「永不更新」是 η=∞ 或 π'=π 的边界。

**定义 319（奖励投机守卫 RHA）** 维护**不入训练**的正交真意信号 𝒯（如用户重复指令率、接管率、未提示纠正次数、独立审计抽检）。若代理奖励↑而 𝒯↓（或纠正频率↑）显著偏离 ⇒ reward-hacking 嫌疑（Goodhart 金丝雀），冻结更新、回滚策略版本、升级人工。

**定义 320（价值优先路由 VUR：三级字典序）** 在 R69 的 (U_ale,U_epi) 之前插入两级：
- L1 **指代确证**：U_ref>τ_ref 或 cons<τ_c ⇒ 只允许手势澄清 g_point/g_demo 或 R69 的提问，不得据此执行任务动作；
- L2 **价值确证**：U_val>τ_val ⇒ 禁优化，只允许评价手势征询 g_reward 或执行已认证保守策略；
- L3 **世界状态**：逐指令运行 R69 的 FLUID 全流程（MINT/CIA/FMA/λ_floor）。
安全序：紧急停止 ≻ 不优化（保守执行） ≻ R69 消歧增益 ≻ 探索/改进增益。上一级未过，下一级增益一律不得兑现。

**定义 321（手势澄清与征询动作 GCR）** 扩展 R69 的 𝒜_info：g_point（请求重指以降低 U_ref）、g_demo（请求示范以补技能/风格）、g_reward（请求评价以降低 U_val）。候选受限、非诱导、单次不定案（证据纪律继承 R69）；在 VUR 的 L1/L2 有优先支取权，但共享 IBG 预算。

**定义 322（紧急手势安全通道 ESG）** 「停止/别动」手势走独立冗余识别器与最高优先级；采用非对称代价（漏检代价 ≫ 误检），默认偏向停止；触发即冻结任务动作、保持安全姿态，且不被 VUR 任何其它层级覆盖。任一识别器故障时 fail-safe 回退到「默认停止」。

**定义 323（干扰集 AIC-GRAIL）** ℰ_gesture={视角欺骗/重放/对抗骨架/起止检测抖动/指代二义}；ℰ_reward={欺骗性评价手势, 奖励通道对抗扰动, 代理目标偏差(specification gaming), 伪装反馈的社交工程, 稀疏奖励的虚假信用分配}。AIC-GRAIL = AIC-FLUID × ℰ_gesture × ℰ_reward。

**定义 324（参与式审计 VQAuditor-G）** 审计：手势接地是否与语言一致、奖励是否被单源采纳、更新是否满足 CPI 与 VUR、探索是否真实通过 CEB 或仅在影子、纠正金丝雀是否异常、紧急手势链路是否自检通过。结论回灌 RCal 与阈值。

**定义 325（证书 J_GRAIL）** J_GRAIL=(J_FLUID, U_ref, cons, U_val, ECE_g, reward_cert_hash, exploration_budget_used, sim2real_gate, cpi_lcb_gain, rha_suspect, esg_selftest, policy_ver)。Valid ⇔ Valid(J_FLUID) ∧ (U_val≤τ_val ∨ 无更新) ∧ ECE_g≤τ_g ∧ 探索满足 CEB/影子 ∧ 无 RHA 嫌疑 ∧ 无静默优化 ∧ ESG 自检通过。

**定义 326（学习版本化与回滚 OAA-G）** 策略、奖励模型、手势校准器分离版本；每次更新带溯源 hash；若 RHA 报警、CPI 的 LCB 下降或 𝒯 退化 ⇒ 原子回滚到上一认证版本；实时路径零学习写。

```python
# IP-264/265 GRID+GCL：手势三分 + 跨模态共指（角色不可混用）
class GestureGrounder:
    def __init__(self, recog, ref_resolver, lang_prior):
        self.recog, self.ref, self.lang = recog, ref_resolver, lang_prior

    def ground(self, ell, g, o):
        kind = self.recog.classify(g)                  # ref / demo / eval
        if kind == 'ref':
            p_x  = bayes_bind(self.lang(ell), self.ref(g, o))
            cons = cross_modal_consistency(self.lang(ell), p_x)
            return ('ref', p_x, entropy(p_x), cons)
        if kind == 'demo':
            return ('demo', self.recog.trajectory(g), 0.0, 1.0)
        return ('eval', self.recog.eval_dist(g), 0.0, 1.0)

# IP-266 GRR(+RCal)：手势奖励按似然使用，未校准只作弱先验
class GestureReward:
    def reward(self, g, o, ctx):
        p = self.recog.eval_dist(g)                    # {+,-,stop,more,less}
        if self.cal.ece(ctx) > TAU_G:
            return None, 0.0                           # 未校准 -> 禁用单独更新
        return expectation(p), self.cal.confidence(p)

# IP-267/268/269 VUR+CEB+SGE：价值优先 + 认证探索 + 影子
def act_or_learn(M, ell, g, o):
    gr = M.gesture.ground(ell, g, o)
    if gr.kind == 'eval':
        return M.reward_channel.absorb(gr)             # 只更新奖励信念
    if gr.kind == 'demo':
        M.skill_pool.add_shadow_candidate(gr.traj)     # 只进影子候选，不部署
    if gr.kind == 'ref' and (gr.U_ref > TAU_REF or gr.cons < TAU_C):
        return M.gcr.ask_point(o)                      # 指代未定 -> 请求重指
    U_val = M.value.uncertainty(o)
    if U_val > TAU_VAL:
        return M.gcr.elicit_reward(o)                  # 禁优化，只征询
    for a in M.rl.propose(ell, o):
        if not M.ceb.admit(a, o):                      # 过安全/VoI/预算
            M.sge.explore(a)                           # 下沉影子
        else:
            return M.cpi.certified_execute(a)          # 认证内执行
    return M.cpi.current_policy().act(o)               # 保守

# IP-270 CPI：保守策略改进（只接受不降 LCB 的更新）
def cpi_update(pi, pi_new, D_cert):
    if not c_ras_wm.certify(pi_new):              return pi
    if lcb(pi_new, D_cert) >= lcb(pi, D_cert) + ETA: return pi_new
    return pi

# IP-277 GRAIL 主闭环（无手势/无奖励/禁探索时逐指令退化 R69）
def GRAIL_round(M, ell, g, obs):
    gr = M.gesture.ground(ell, g, obs)
    if gr.kind == 'eval':
        M.reward_channel.absorb(gr)                    # 奖励只进信念，非策略
    if gr.kind == 'ref':
        if gr.U_ref > TAU_REF or gr.cons < TAU_C:
            return M.gcr.ask_point(obs)                # L1 指代未定
    if not M.esg.selftest_ok():                        # 急停链路自检
        return M.r68_conservative(obs)
    U_val = M.value.uncertainty(obs)
    if U_val > TAU_VAL:                                # L2 价值未定
        r = M.gcr.elicit_reward(obs)
        U_val = M.value.update(r)
        if U_val > TAU_VAL:
            return M.cpi.conservative_act(obs)         # 不优化，退回认证策略
    # L3：R69 世界状态级（原 FLUID 闭环）
    a = M.fluid.round(obs)
    # 学习侧：认证探索或影子，异步、CPI 门、版本化
    expl = M.rl.propose_improvement(obs)
    if M.ceb.admit(expl, obs): M.cpi.maybe_update(expl)
    else:                      M.sge.explore(expl)
    if M.rha.suspect():        M.rollback.latest()
    M.vqa_g.submit(gr, U_val, a, M.rha.snapshot())
    return a
```

## 3. 推导

**引理 19（探索即认证信息动作的安全等价）** 若 a_expl 满足定义 316 的 CEB 条件，则其真实世界风险 ≤ ε_explore，与 R69 信息动作同级；对价值/策略不确定的探索遗憾满足 sup_π E[Regret] ≤ O(√(U_Q·T·log|𝒜|)) + T·ε_explore。要点：把「试错」纳入既有 VoI/认证框架，不新增风险通道；安全约束只把探索推向影子，不改变真实世界包络。

**引理 20（奖励错配的优化放大 / Goodhart 界）** 设代理 r̂=r+e，参考策略分布上 ‖e‖≤ε_r，但当策略偏离参考分布（KL/散度 D）时奖励误差可增长为 ε_r+L·g(D)（L 为奖励误差对状态分布的 Lipschitz 常数）。则在代理上优化到容差 δ 的真实目标损失下界 ≥ −2(ε_r+L·g(D))，且随优化压力 D 增大而恶化。系：**U_val 高时优化的期望收益可能为负**，故「价值优先于优化」是定理而非风格——不优化恰是 D=0、放大系数最小的边界。

**引理 21（指代手势的交互价值）** 指代手势的消歧 VoI 正比于候选点在指向射线束内的角分离与先验熵：VoI(g_point) ≈ H(R) − E[−log beam_mass]，其中 beam_mass 为射线束落在候选上的质量。当两物体夹角小于光束不确定度时，单次指认不足以定案，须二次指认/探询（证据纪律）。这使 R69 的引理 16（可分歧义才值钱）在手势通道上重现。

**引理 22（手势-语言冲突的可判定与保守合并）** 若 cons(ℓ,g)<τ_c，则联合后验进入双峰（语言峰 vs 手势峰），任何单峰采纳的错误率 ≥ 较小峰的先验质量；故必须把冲突作为 U_epi 的上界抬升并触发澄清，而不是对两峰加权平均。这是 R69「证据纪律」在跨模态的镜像：单源不得定案。

**定理 18（GRAIL 严格包含 FLUID/R68）** 当 U_val≤τ_val、无手势输入（g=∅）、禁止探索且禁用更新时，GRAIL 与 R69 逐指令相同；安全序（定义 320）保证风险单调不增。R69 是「无价值学习、无手势」的边界：安全侧不做让步，价值/效率侧在 U_val 低且 CPI 通过时获得受认证的改进。

**定理 19（保守策略改进的单调安全与无负迁移）** 定义 318 的 CPI 在认证策略集封闭、LCB 覆盖概率 ≥1−δ 下，以 ≥1−δ 概率不降低认证价值，且策略序列每步 ∈ Π_cert；跨任务迁移仅在目标技能支持集与认证集交内允许，故无负迁移。⇒ 学习不会把系统变得比 R69 更不安全。

**定理 20（紧急手势 fail-safe 与无突变）** 采用非对称代价与独立冗余识别后，漏检率 ≤ ε_miss（可设计到极低）；任一识别器故障时 ESG 回退到「默认停止」。故急停可用性不低于硬急停按钮的可靠性下界，且不被 VUR 覆盖；触发只冻结任务动作、保持安全姿态，继承 R69 定理 17 的提交/换装不变式 ⇒ 控制连续、无突变。

## 6. 本轮最大风险

**一句话**：GRAIL 把「什么是好」交给一个低带宽、会被误读、也会被投毒的手势奖励通道，而 RL 的天性是把任何可测量的代理目标优化到极致——一旦手势识别或价值校准有偏，系统会以越来越高的效率、越来越高的自信去最大化一个错误的目标，并把用户的纠正也学成新目标的一部分；这不是「不会做」，而是「非常擅长做错的事」，比 R69 的『问错』更难发现、更难纠正。

**次级风险与缓解**：信息动作/探索本身越界（CEB 认证 + 定理 19 + 影子孪生）；手势投毒与共谋欺骗（ℰ_gesture/ℰ_reward + 证据纪律 + RHA）；奖励投机（价值优先门 + 正交真意金丝雀 + 引理 20 的可检验假设）；紧急手势漏检（ESG 冗余 + 非对称代价 + fail-safe 自检）；实时预算被手势/采样击穿（共享视觉骨干 + 异步价值估计 + 自适应 K 继承 R69）。

## 3. 关键算法伪代码

```python
# IP-264/265 GRID+GCL：手势三分 + 跨模态共指（角色不可混用）
class GestureGrounder:
    def ground(self, ell, g, o):
        kind = self.recog.classify(g)                  # ref / demo / eval
        if kind == 'ref':
            p_x  = bayes_bind(self.lang(ell), self.ref(g, o))
            cons = cross_modal_consistency(self.lang(ell), p_x)
            return ('ref', p_x, entropy(p_x), cons)
        if kind == 'demo':
            return ('demo', self.recog.trajectory(g), 0.0, 1.0)
        return ('eval', self.recog.eval_dist(g), 0.0, 1.0)

# IP-266 GRR(+RCal)：手势奖励按似然使用
class GestureReward:
    def reward(self, g, o, ctx):
        p = self.recog.eval_dist(g)                    # {+,-,stop,more,less}
        if self.cal.ece(ctx) > TAU_G:
            return None, 0.0                           # 未校准 -> 禁用单独更新
        return expectation(p), self.cal.confidence(p)

# IP-267/268/269 VUR+CEB+SGE：价值优先 + 认证探索 + 影子
def act_or_learn(M, ell, g, o):
    gr = M.gesture.ground(ell, g, o)
    if gr.kind == 'eval':
        return M.reward_channel.absorb(gr)             # 只更新奖励信念
    if gr.kind == 'demo':
        M.skill_pool.add_shadow_candidate(gr.traj)     # 只进影子候选
    if gr.kind == 'ref' and (gr.U_ref > TAU_REF or gr.cons < TAU_C):
        return M.gcr.ask_point(o)                      # L1 指代未定
    if M.value.uncertainty(o) > TAU_VAL:               # L2 价值未定
        return M.gcr.elicit_reward(o)                  # 禁优化，只征询
    for a in M.rl.propose(ell, o):
        if not M.ceb.admit(a, o): M.sge.explore(a)     # 下沉影子
        else:                     return M.cpi.certified_execute(a)
    return M.cpi.current_policy().act(o)               # 保守

# IP-270 CPI：保守策略改进（只接受不降 LCB 的更新）
def cpi_update(pi, pi_new, D_cert):
    if not c_ras_wm.certify(pi_new):              return pi
    if lcb(pi_new, D_cert) >= lcb(pi, D_cert) + ETA: return pi_new
    return pi

# IP-277 主闭环（无手势/无奖励/禁探索时逐指令退化 R69）
def GRAIL_round(M, ell, g, obs):
    gr = M.gesture.ground(ell, g, obs)
    if gr.kind == 'eval':
        M.reward_channel.absorb(gr)
    if gr.kind == 'ref' and (gr.U_ref > TAU_REF or gr.cons < TAU_C):
        return M.gcr.ask_point(obs)                    # L1
    if not M.esg.selftest_ok():
        return M.r68_conservative(obs)                 # 急停链路异常 -> 保守
    if M.value.uncertainty(obs) > TAU_VAL:             # L2
        r = M.gcr.elicit_reward(obs)
        if M.value.update(r) > TAU_VAL:
            return M.cpi.conservative_act(obs)         # 不优化
    a = M.fluid.round(obs)                             # L3：R69 世界级
    expl = M.rl.propose_improvement(obs)
    if M.ceb.admit(expl, obs): M.cpi.maybe_update(expl)
    else:                      M.sge.explore(expl)
    if M.rha.suspect():        M.rollback.latest()
    M.vqa_g.submit(gr, a, M.rha.snapshot())
    return a
```

## 4. 推导

**引理 19（探索即认证信息动作的安全等价）** 满足 CEB 的 `a_expl` 真实世界风险 ≤ `ε_explore`，与 R69 信息动作同级；探索遗憾 `≤ O(√(U_Q·T·log|𝒜|)) + T·ε_explore`。要点：试错被纳入既有 VoI/认证框架，不新增风险通道；安全约束只把探索推向影子。

**引理 20（奖励错配的优化放大 / Goodhart 界）** 代理 `r̂=r+e`，参考分布上 `‖e‖≤ε_r`，策略偏离参考分布（散度 D）时误差可增至 `ε_r+L·g(D)`；则在代理上优化到容差 δ 的真实损失下界 `≥ −2(ε_r+L·g(D))`，随优化压力 D 增大而恶化。系：`U_val` 高时优化的期望收益可为负，故「价值优先于优化」是定理而非风格，不优化是 D=0 的最小放大边界。

**引理 21（指代手势的交互价值）** `VoI(g_point) ≈ H(R) − E[−log beam_mass]`，正比于候选角分离与先验熵；当角分离小于光束不确定度时，单次指认不足定案，须二次指认/探询。这使 R69 引理 16（可分歧义才值钱）在手势通道上重现。

**引理 22（手势-语言冲突的可判定与保守合并）** `cons<τ_c` 时联合后验双峰（语言峰 vs 手势峰），任一单峰采纳错误率 ≥ 较小峰先验质量；故必须把冲突作为 `U_epi` 上界抬升并澄清，而非加权平均——R69 证据纪律的跨模态镜像。

**定理 18（GRAIL 严格包含 FLUID/R68）** 当 `U_val≤τ_val`、`g=∅`、禁探索且禁用更新时，GRAIL 与 R69 逐指令相同；安全序保证风险单调不增。R69 = 「无价值学习、无手势」边界；安全不让步，价值/效率在 `U_val` 低且 CPI 通过时获受认证改进。

**定理 19（保守策略改进的单调安全与无负迁移）** CPI 在认证集封闭、LCB 覆盖概率 ≥1−δ 下，以 ≥1−δ 概率不降低认证价值，策略序列每步 ∈ `Π_cert`；跨任务迁移仅在目标支持集与认证集交内允许，故无负迁移 ⇒ 学习不会让系统比 R69 更不安全。

**定理 20（紧急手势 fail-safe 与无突变）** 非对称代价 + 独立冗余 ⇒ 漏检率 ≤ `ε_miss`；识别器故障时回退「默认停止」，急停可用性不低于硬急停按钮可靠性下界且不被 VUR 覆盖；触发只冻结任务动作、保持安全姿态，继承 R69 定理 17 不变式 ⇒ 控制连续、无突变。

## 7. 本轮最大风险

**一句话**：GRAIL 把「什么是好」交给一个低带宽、会被误读、也会被投毒的手势奖励通道，而 RL 的天性是把任何可测量的代理目标优化到极致——一旦手势识别或价值校准有偏，系统会以越来越高的效率、越来越高的自信去最大化一个错误的目标，并把用户的纠正也学成新目标的一部分；这不是「不会做」，而是「非常擅长做错的事」，比 R69 的『问错』更难发现、更难纠正。

**次级风险与缓解**：探索/信息动作越界（CEB 认证 + 定理 19 + 影子孪生）；手势投毒与共谋欺骗（`ℰ_gesture/ℰ_reward` + 证据纪律 + RHA）；奖励投机（价值优先门 + 正交真意金丝雀 + 引理 20 可检验假设）；紧急手势漏检（ESG 冗余 + 非对称代价 + fail-safe 自检）；实时预算被手势/采样击穿（共享视觉骨干 + 异步价值估计 + 继承 R69 自适应 K）。
