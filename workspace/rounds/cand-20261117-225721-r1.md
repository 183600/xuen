# 第 2 轮（承接第 1 轮 UniBot-SAGE；本轮灵感：「低延迟推理」×「LoRA」）

> **承接关系**：本轮在第 1 轮 UniBot-SAGE（接地层 / 技能层 / 适应层 + 工程层）之上做「深化 + 修剪」，不推倒重来。第 1 轮 §8 已预置两条深化方向：把抓握升级为时序状态机、把代理评测与专家划分对齐；本轮用「低延迟推理 × LoRA」把这两条方向拧到同一个更硬的约束上：**时间**。
> **检索纪律**：不新增外部网页检索，沿用第 1 轮已核实的 UniBot 事实（teaser 榜仍按 teaser 处理，不当作官方终稿）。本轮新增的是在本地官方数据缓存 `exp/duo_rows_cache/`（15/32 个任务的逐帧记录，30 Hz，每任务 30 页 × 100 帧）上做的**新的定量核查**，见 §2 与产物区 §9；数字可复算。

## 0. 一句话直觉

- **「低延迟推理」**：延迟不是要"消掉"的工程噪声，而是**控制回路里的一段真实盲区**。真正的问题不是"模型能跑多快"，而是**把有限的时间预算花在哪一段相位上**：搬运可以开环，插入必须闭环。
- **「LoRA」**：低秩不是"更小的模型"，而是**可合并的差异**。如果技能路由 = 选一个低秩增量，那么路由的正确实现是**"合并"而非"逐步门控"**——合并后仍是一份稠密权重，天然满足"单 checkpoint、单 API"。
- **合成**：**UniBot-LoRAC**（LoRA-Routed, Reflex-Augmented Cascade；LoRA 路由 · 反射增强级联）= **慢思考**（低频 VLA，任务/相位 LoRA 在块边界合并）× **快反射**（30 Hz 小残差修正器）× **延迟证书**（把 p99 与开环深度变成可审计量）。

## 1. 两个灵感的第一性原理

### 1.1 低延迟推理 → 延迟是控制变量，不是常数

**直觉**：一个机械臂的"反应慢"从来不只因为模型慢。即使算力无限，关节也不是瞬间到位——指令下去，关节要"走一小步"。所以延迟是**回路固有的**；模型只是叠加在固有滞后上的一层。既然如此，正确的提问不是"如何把推理压到 0 ms"，而是：**给定预算，多少时间用来"想"、多少用来"改"、多少用来"等"**。

**严谨形式**：设控制周期 `τ`（本地数据实测中位 `τ = 1/30 s = 33.3 ms`）。一次决策的端到端延迟

`L = t_obs + t_model + t_head + t_comm`，

其**开环深度**为 `k = ⌈L/τ⌉`：决策返回后，有 `k` 个控制步是在"没有新观测"的情况下执行的。于是延迟的代价可被唯一地写成**开环预测误差** `e(k)`。本轮在官方数据上直接测出了 `e(k)`（见 §2）：`e(k)` 随 `k` 单调上升；而一个只用本体感受（无视觉）的线性"反射"就能把它降低 13%–41%。这就把"低延迟"从一句口号变成了**可优化的曲线**。

由此得到本轮的核心命题：

> **延迟不该被"平均地"压缩，而该被"按相位"分配。** 接触/插入相位状态发散快 → 预算给反射；搬运相位状态慢变 → 预算给开环块。

### 1.2 LoRA → 低秩不是"更小的模型"，是"可合并的差异"

**直觉**：LoRA 说的是 `W' = W + BA`，`BA` 低秩。它的工程含义常被误读成"省参数"；但对我们真正有用的是另一面：**两个 LoRA 的加权和仍是低秩增量，因此可以精确地先合并成一份权重再服务**。这直接解决第 1 轮留下的最大合规隐患（Q3）：技能路由不必暴露成"每步在多个专家间门控"，而可以在块边界把它**算进权重**，服务时永远只有一份稠密权重 = 严格意义上的"单模型、单 checkpoint"。

**严谨形式**：设技能增量库 `{Δ_k = B_k A_k}`，路由权重 `g_k`，则

`W_serve = W + Σ_k g_k B_k A_k`，

其秩 `rank ≤ Σ_k g_k≠0 rank(Δ_k)`。合并是一次矩阵乘加，成本与参数规模线性相关；**每步推理零额外开销**，切换成本只在"路由变化时"发生。配合影子权重双缓冲与原子切换，合并可以在上一个 chunk 执行期间完成，从而**不出现在 per-step 延迟里**。

本轮用数据给 LoRA 定了两个边界（§2）：
1. **行为是低秩的**：动作增量的 90% 方差落在 4 维（16 维动作里），每任务均值偏移只需 4–5 维即可解释 90% → LoRA 秩 `r≈4–8` 足够，便宜且可合并。
2. **性能不是低秩的**：teaser 榜 8 模型 × 32 任务的中心化矩阵需 7/8 个奇异值才到 90% → 技能**不能用少数几个专家压缩**。所以 LoRA 库应按**相位/接触 regime**（低维行为模式）索引，而不是按任务索引。这条修正直接改写了第 1 轮 IP-01 的路由对象。

### 1.3 合成：为什么是"级联"而不是"更快的单模型"

单模型要同时满足三件互相拉扯的事：**(a) 低频大模型保证语义正确**、**(b) 高频小模型保证接触精度**、**(c) 单 checkpoint 保证合规**。LoRA 让 (c) 与 (a) 不冲突（合并即单权重）；级联让 (a) 与 (b) 各取所需（不同频率、不同容量）。因此本轮不是"把 VLA 蒸馏得更小"，而是**把时间尺度分开**：慢的负责"做什么"，快的负责"此刻偏了多少"。

## 2. 本轮对第 1 轮的量化修订（官方数据本地核查）

数据：`exp/duo_rows_cache/*.json`，15 个任务（官方 32 中的子集）× 每任务 30 页 × 每页 100 帧，`observation/action` 字段完整。所有页内相邻帧做差分；跨页边界因 episode 重置被排除。归一化用页内动作标准差 `σ≈0.384`。

| 观测 | 数值 | 对设计的含义 |
|---|---|---|
| 控制频率 | `dt` 中位 33.3 ms → **30 Hz** | 每步预算 33 ms；105 ms 推理 ⇒ 开环深度 `⌈105/33.3⌉ = 4` |
| 关节一阶伺服 | `Δq ≈ κ(a−q)`，`κ=0.295`，`corr=0.729` ⇒ 时间常数 `≈0.095 s` | **执行器自身就有约 3 步滞后**；指令必须超前补偿（L14） |
| 动作增量低秩 | 90% 方差在 **4/16** 维；每任务 90% 在 2–5 维 | LoRA 秩 `r≈4–8` 足够；合并成本极低 |
| 任务均值低秩 | 15 个任务均值偏移：80% 需 2 维、90% 需 4 维、95% 需 5 维 | 任务层适配可以是**极小**的低秩增量 |
| 任务可分性 | 任务间方差 / 任务内方差（Fisher）仅 **0.078** | **任务 token 单独解释力很弱**；路由必须落到相位/接触 regime |
| 性能矩阵秩 | 8×32 中心化榜：90% 需 **7/8** 个奇异值 | 技能**不可**压成少数专家；按任务做 MoE 的收益来自"专长异质"而非"低秩" |
| 开环预测误差 | 线性外推 RMSE/σ：h=1→0.068，h=4→0.279，h=8→0.647，h=16→1.45 | 长 chunk 必须配反射；h>4 误差已不可忽略 |
| 反射增益 | 仅用本体感受+历史动作的线性修正器：h=1 降 **12.7%**，h=4 降 **20.0%**，h=8 降 **27.4%**，h=16 降 **41.3%** | 廉价反射可显著延长可用开环深度；带视觉只会更好 |
| 大修正稀疏 | `|Δa|>0.5` 仅 1.7%，`>1.0` 仅 0.08%（p99=0.533） | 反射可**事件触发**，平时几乎零算力 |
| 动作平滑性 | lag-1 自相关：动作 0.9995，增量 0.792 | 外推可行，但增量可预测性随 h 快速衰减 |

**三条修订（本轮必须写进设计）**：

- **R1（路由对象下移）**：第 1 轮把 IP-01 的技能路由押在"任务 token"上；Fisher=0.078 说明**任务身份只解释 7.8% 的动作方差**。路由对象应从"任务"下移到"相位/接触 regime"（reach / grasp / insert / release + 是否接触），任务 token 只作为弱先验。
- **R2（缝合不够，要反射）**：第 1 轮 IP-03 的 chunk 缝合只保证边界 C0/C1 连续，但**不修正块内的开环漂移**；h=8 时误差已达 0.65σ。必须加一个 30 Hz 的残差反射器，缝合与反射是两件事。
- **R3（在线更新替换为合并路由）**：第 1 轮 IP-04 的"受限在线权重更新"合规风险高。LoRA 提供更安全的替代：**离线学好的低秩增量 + 块边界合并 + 双缓冲 + 可回滚**，不做无标签的步内梯度更新。

## 3. 研究问题（本轮增量）

- **Q6（延迟去哪了）**：端到端延迟在 obs 编码 / 主干推理 / 动作头 / 通信 / 缝合各占多少？p50 与 p99 的差是否主要来自"偶发大修正"而非稳态计算？
- **Q7（开环深度可换多少成功率）**：给定实测 `e(k)`，把 chunk 深度从 8 降到 4、或从 4 升到 8，终端成功率如何变？反射能把"可接受深度"推到多长？
- **Q8（合并路由是否等价且更快）**：`W + Σ g_k B_k A_k` 与"每步门控"在精度上是否等价？合并的切换尖峰能否被双缓冲完全隐藏？
- **Q9（LoRA 该按什么索引）**：按任务 vs 按相位/regime，哪个路由更省且更准？秩 `r` 的边际收益在哪饱和？多 LoRA 合并是否互相干扰（遗忘）？
- **Q10（低延迟是否伤害泛化）**：反射器是在本体感受上学的惯性外推；在未见物体上它可能"又快又错"。如何用一个可审计的闸门识别这种情形并回退到慢而稳的基线？

## 4. 设计原则（在第 1 轮 P1–P6 上增补）

- **P7 延迟是预算，不是常数**：任何模块都必须声明"每步耗时上界 + 开环深度代价"；不能声明者不得进入高频路径。
- **P8 路由即合并**：技能切换必须在块边界完成，且服务时只有一份稠密权重；禁止"每步在 K 个专家间软门控"作为默认形态。
- **P9 快必须可回退**：反射器的每一次介入都要有置信度与回退；宁可慢而稳，不得快而错。

## 5. 系统形态（LoRAC 五层）

1. **慢策略（低频）**：冻结的通用 VLA 主干 + 任务/相位 **LoRA 增量库**。在块边界按当前 `z_phase` 选择并**合并**增量到影子权重，原子切换。
2. **快反射（30 Hz）**：一个 ≤3 ms 的残差修正器，输入腕部小图 + 本体感受 + 上一动作增量，输出对"外推动作"的修正量；事件触发（大修正稀疏）。
3. **开环调度器**：按相位选 chunk 深度 `T_a`，并显式报告由此产生的开环深度 `k` 与 `e(k)`。
4. **伺服超前器**：用辨识出的 `κ` 把"期望下一状态"反解成"此刻指令"（U14/L14），补偿约 3 步固有滞后。
5. **延迟证书**：记录每段延迟、合并耗时、切换尖峰、开环深度、降级次数，产出可导出的 p50/p99 与预算占用图——对齐官方"延迟与动作规律性"的可信度口径。

**退化链（在上一轮基础上加两级）**：
Level-5 合并路由失败 ⇒ 用离线预合并的单一 LoRA；
Level-6 反射器置信度低或 OOD 告警 ⇒ 反射权重置零，退回"慢策略 + 长 chunk"；
Level-7 全链路异常 ⇒ 退回第 1 轮的最小基线（能跑通、可信度合规）。

## 7. 本轮最大风险

**一句话**：一旦把"低延迟"设为目标，反射器可能用**高频的错误动作**替换低频的正确动作——它在本地数据上学到的是本体感受的惯性外推而非接触物理，到了未见物体上，延迟被藏住了、错误却被放大，而我们的离线指标恰好测不出这一点。

## 8. 下一轮迭代计划

- **深化**：把反射器从"线性残差"升级为"接触感知的小网络"，并让它输出**不确定度**；用不确定度驱动事件触发（而不是固定阈值）。
- **对齐**：把"相位/regime 索引"与第 1 轮 IP-06 的六因子分解对齐——每个 regime 恰好对应一段因子链。
- **修剪预案**：若真机上"合并路由"相对"固定单 LoRA"的增益 <1.0 分，则**放弃路由、保留单 LoRA + 反射**；反射器的投入以"真机 A/B 上插入类任务 ≥+2 分"为唯一门槛，否则砍掉。

## 0. 本轮结论摘要

**一句话路线**：在 UniBot-SAGE 之上，把"低延迟"实现为**延迟预算分配**（慢 VLA 低频 + 30 Hz 反射器 + 相位自适应 chunk），把"LoRA"实现为**可合并的技能增量**（trunk 低秩增量服务、动作头合并、块边界切换），两者共享同一组可观测量（开环深度、伺服残差、增量秩），因此几乎不额外花钱。

**三条量化依据（全部本地可复算，见 §9）**：

| 证据 | 数值 | 推出的设计 |
|---|---|---|
| 控制 30 Hz；关节一阶伺服 `κ=0.295`，`corr=0.729` | 执行器本征滞后 ≈0.095 s ≈ 3 步 | 必须做**伺服超前补偿**（U14/L14），否则再快的模型也"慢半拍" |
| 开环误差 `e(k)`：h=4→0.28σ，h=8→0.65σ；廉价反射降 20%/27% | 长 chunk 的代价可测、可削减 | **chunk 深度 + 反射** 是一对可调的延迟-精度旋钮 |
| 动作增量 90% 在 4/16 维；任务均值 90% 在 4 维；但榜单性能矩阵 90% 需 7/8 维 | 行为低秩、性能高维 | LoRA 秩 `r≈4–8` 够用；但**按任务做专家是错的**，应按相位/接触 regime |

**与第 1 轮的关系**：IP-01 从"任务 token MoE"改为"相位/regime 的 LoRA 合并路由"；IP-03 拆成"缝合（边界）+ 反射（块内）"；IP-04 的高风险在线更新被 LoRA 合并替代；IP-02/IP-06 保留并直接受益；IP-08 升级为延迟证书。

| **IP-14** | RegimeBank 相位/接触 regime 库 | P1 | 用少量低秩 regime 增量替代"每任务专家"；每 regime 服务 ≥2 任务 | 数据 | 相对单 LoRA ≥+1.5 分；regime 数 ≤8；无退化 |
| **IP-15** | EventCompute 事件触发算力 | P2 | 大修正稀疏（0.08%），平时跳过重算力；只在事件窗口加频 | 工程 | 平均算力降 ≥30%；成功率不降 |

> **P0 构成本轮 MVP**：IP-09 + IP-10 + IP-11（叠加第 1 轮 IP-02/IP-03/IP-06）。P1 视真机 A/B 推进。P2 有余量再做。

## 2. 创新点详述

### IP-09 · LatencyLedger 延迟预算与开环深度核算（P0）

- **动机**：官方明确会采集 per-step 延迟及其波动并可能据此评估可信度；同时 30 Hz 控制 + 约 105 ms 级 VLA 推理意味着**评测时本来就存在开环深度**。不做核算就等于把一段盲区交给运气。
- **与现有做法的差异**：多数提交只报"能跑"；我们把延迟拆成 `obs 编码 / 主干 / 动作头 / 通信 / 缝合` 五段，逐段设上界，并把 chunk 深度显式换算成开环误差 `e(k)`。
- **落地**：① 用官方 `run_server.py` + `run_client.py` 复刻闭环，打点五段延迟；② 对每段拟合 p50/p99；③ 定义预算表（见 §6），超预算即降级；④ 输出"预算占用 × 相位"热图。
- **风险**：评测端网络拓扑未知 ⇒ 先测、不假设；不允许任何"利用未声明插值/执行语义"的优化。

### IP-10 · MergeRouter LoRA 合并路由（P0）

- **动机**：第 1 轮 Q3 的合规隐患是"多专家是否算多模型"。LoRA 给出一个数学上干净的答案：**路由 = 选一个低秩增量，而低秩增量可以合并进权重**（L8）。
- **与现有做法的差异**：
  - 常见做法 A：多个独立策略 / 多个 checkpoint → 可能违规；
  - 常见做法 B：每步对 K 个专家软门控 → 每步 K 倍算力、且动作抖动；
  - 本轮：**trunk 用"单适配器低秩增量服务"**（`Wx + B(Ax)`，仅 +1% 算力），**动作头用"真合并"**（小矩阵，块边界一次），任意时刻只有一个适配器生效。
- **双形态合规**：
  - **形态-1（推荐）**：一个 checkpoint 内含 base + adapter bank；服务时 `Wx + BAx`，仍是"一份模型、一个 API、单一激活路径"。
  - **形态-2（最严格）**：episode 开始时（`reset`）把任务适配器**预合并**成稠密权重，之后冻结；相位切换只改动作头。这是字面意义上的"单一稠密权重"。
- **所需资源**：数据=官方 32 数据集；算力=LoRA 微调（小）；接口=无新增字段。
- **风险**：多适配器合并干扰（L16）⇒ 正交化 + 小秩 + 一次只激活一个；trunk 低秩服务的 +1% 延迟需实测确认。

### IP-11 · ReflexCorrect 30 Hz 残差反射器（P0）

- **动机**：本地数据显示 h=8 的开环误差达 0.65σ；而仅用本体感受+历史动作的**线性**修正就能降 27.4%（h=8）、41.3%（h=16）。这说明块内漂移是**可预测的**，不需要每步调用大模型。
- **与现有做法的差异**：第 1 轮 IP-03 只缝合边界；本 IP 修正块内。且反射器**事件触发**——大修正极稀疏（`|Δa|>1.0` 仅 0.08%），平时几乎零算力。
- **技术形态**：输入腕部小图（低分辨率）+ 双臂本体 + 上一动作增量 + 伺服残差；输出对外推动作的残差 `δa` 与不确定度 `u`。仅当 `u<τ_u` 且 `|δa|` 大时介入，介入量有上界。
- **落地**：① 用官方数据构造"外推残差"监督对；② 训练小型 CNN/MLP（目标 ≤3 ms）；③ 标定不确定度；④ 真机插入任务 A/B。
- **风险**：**又快又错**（本轮最大风险）⇒ 不确定度门控 + 介入上界 + OOD 告警即置零。

### IP-12 · ServoLead 伺服超前补偿（P1）

- **动机**：`Δq ≈ κ(a−q)` 且 `κ=0.295` ⇒ 时间常数 ≈0.095 s。即使零推理延迟，执行器也滞后约 3 步。
- **做法**：把"下一状态目标 `q*`"反解为"此刻指令"：`a_t = q_t + κ^{-1}(q* − q_t) − (1−κ)/κ · \hat{ε}`，`κ^{-1}≈3.39`。只对均值做超前，不对噪声放大。
- **风险**：超前过度会引起超调振荡 ⇒ 用速度限幅与低通残差约束。

### IP-13 · LatencyCertificate 延迟证书（P1）

- **动机**：官方把"延迟波动 / 动作统计规律性"作为可信度信号。我们把它变成**主动自证**：结构化地证明"慢得稳定、快得有界"。
- **产物**：五段延迟直方图、p50/p99、合并耗时分布、切换尖峰计数、开环深度逐相位统计、降级次数、动作 jerk 上界告警。
- **风险**：过度限幅降低成功率 ⇒ 限幅阈值由数据分布定，且只作用于残差。

### IP-14 · RegimeBank 相位/接触 regime 库（P1）

- **动机**：Fisher=0.078 说明任务身份几乎不能解释动作方差；真正变化的是相位/接触 regime。而行为增量低秩（90% 在 4 维）说明少量 regime 就够。
- **做法**：定义 ≤8 个 regime（reach / grasp-open / grasp-closed / lift / transport / align-near / insert-contact / release），每个 regime 一个低秩增量；任务 token 仅作弱先验。约束"每个 regime 服务 ≥2 个任务"防过拟合。
- **风险**：regime 分类器错判 → 合并错增量 ⇒ 低置信时回退通用增量。

### IP-15 · EventCompute 事件触发算力（P2）

- **动机**：大修正稀疏（1.7% 的步 `|Δa|>0.5`）。大部分时间不需要重算。
- **做法**：以 `|Δa|`、伺服残差、反射器不确定度为事件信号；事件窗口内提高反射频率/启用视觉；窗口外只用外推。
- **风险**：事件漏检 ⇒ 双阈值（低阈值唤醒、高阈值介入）+ 最大静默时长。

## 3. 符号与定义（U13–U24）

| 符号 | 含义 |
|---|---|
| `τ` | 控制周期（实测 1/30 s ≈ 33.3 ms） |
| `L_t` | 第 t 次决策的端到端延迟 |
| `k_t` | 开环深度 `⌈L_t/τ⌉` |
| `e(k)` | 开环 k 步的动作预测误差（RMSE/σ） |
| `Δ_k=B_kA_k` | 第 k 个低秩技能/regime 增量 |
| `g_k` | 路由权重（默认 one-hot） |
| `W_serve` | 实际服务权重 |
| `δa, u` | 反射修正量与不确定度 |
| `κ` | 伺服增益（实测 0.295） |
| `σ` | 页内动作标准差（实测 0.384） |
| `Z_r` | regime token |
| `Cert` | 延迟证书 |

**定义 U13（延迟预算）** `L_t = t_obs + t_model + t_head + t_comm + t_stitch`，且要求 `L_t ≤ L_max`（默认 105 ms，可配置）。
**定义 U14（开环深度与误差）** `k_t=⌈L_t/τ⌉`；`e(k)=E[‖a_{t+k}−Ŝ_k(a_{≤t})‖]/σ`，`Ŝ_k` 为外推算子。
**定义 U15（LoRA 增量库）** `{(B_k,A_k)}_{k=1..K}`，`B_k∈R^{d×r_k}`，`A_k∈R^{r_k×d}`，`r_k≪d`。
**定义 U16（路由即合并）** 给定 one-hot 或稀疏 `g`，`W_serve = W + Σ_k g_k B_k A_k`；trunk 允许延迟合并（低秩服务），动作头允许即时合并。
**定义 U17（双形态合规）** 形态-1：`W_serve` 以低秩增量形式服务；形态-2：`reset()` 时预合并为稠密权重并冻结。
**定义 U18（反射器）** `(δa,u)=R_ψ(o^{wrist}_t, q_t, a_{t-1})`，仅当 `u<τ_u ∧ ‖δa‖>τ_δ` 时叠加，`‖δa‖≤δ_max`。
**定义 U19（事件触发）** 事件 `E_t = 1[‖Δa_t‖>ε_1 ∨ ‖ε_servo‖>ε_2 ∨ u<τ_u]`；事件外跳过视觉与重算。
**定义 U20（伺服超前）** `a_t = q_t + κ^{-1}(q*_{t+1} − q_t)`（忽略噪声项时）。
**定义 U21（regime token）** `Z_r = argmax_r P(r | o_{t-k:t})`，`r∈{reach,grasp_open,grasp_closed,lift,transport,align,insert,release}`。
**定义 U22（秩预算）** `r = max_k r_k`，目标 `r∈[4,8]`；合并后有效秩 `≤Σ_k r_k`。
**定义 U23（延迟证书）** `Cert = {p50,p99 各段, t_merge 分布, 尖峰计数, k_t 分布, 降级计数}`。
**定义 U24（可回退反射）** 若 `u≥τ_u` 或触发 OOD 告警，则令 `δa=0`；系统退化为纯慢策略。

## 4. 引理与推导（L8–L16）

**引理 L8（合并线性性 ⇒ 单权重等价）** 对任意权重 `g_k≥0`，`W + Σ_k g_k B_k A_k` 是单个 `d×d` 矩阵，其秩 `≤ rank(W) + Σ_k g_k≠0 r_k`。因此"选增量"与"合并后服务"在数学上等价；软路由不需要 K 份前向。∎
*推论*：若一次只激活一个增量（one-hot），则 `W_serve` 与"加载一个 LoRA 后的模型"逐元素相同——这正是"单 checkpoint、单 API"的严格含义。

**引理 L9（合并隐藏条件）** 设块剩余执行时间 `(T_a−1)τ`，合并耗时 `t_m`。若 `t_m + t_swap ≤ (T_a−1)τ`，且采用双缓冲/预合并，则合并不进入 per-step 延迟。对动作头，`t_m` 在毫秒级；对 trunk，采用低秩增量服务时 `t_m=0`（只需切换 `A,B` 指针）。∎

**引理 L10（开环误差单调增长）** 在动作增量 lag-1 自相关 `ρ≈0.79` 的平稳假设下，`e(k)` 随 `k` 单调上升；本地实测：`e(1)=0.068σ, e(4)=0.279σ, e(8)=0.647σ, e(16)=1.45σ`。⇒ chunk 深度不是越大越好，存在由 `e(k)` 与失败代价决定的最优 `k*`。∎

**引理 L11（反射增益下界）** 若残差 `a_{t+k}−Ŝ_k` 中可由 `(q_t, a_{≤t})` 线性解释的比例为 `ρ_k`，则反射把 `e(k)` 缩小 `(1−ρ_k)`。本地用线性修正器实测 `ρ`：`h=1:12.7%`、`h=8:27.4%`、`h=16:41.3%`；带视觉的 `ρ` 只会更高。故反射对长 chunk 的边际价值更大。∎

**引理 L12（任务 token 的解释力上界）** 设任务间/任务内方差比为 `F`，则任务身份解释的动作方差比例 `=F/(1+F)`。本地 `F=0.078` ⇒ 仅 **7.2%**。因此"按任务路由"的动作层收益上界很低；路由必须落到相位/regime。∎

**引理 L13（行为低秩 ≠ 性能低秩）** 行为侧：动作增量 90% 方差在 4/16 维。性能侧：teaser 榜 8×32 中心化矩阵 90% 方差需 7/8 个奇异值。⇒ 低秩只保证"适配便宜"，不保证"少数技能够用"。故 LoRA 库按 regime 索引，而**不是**按任务/性能索引。∎

**引理 L14（伺服超前的必要性）** 由 `q_{t+1}=q_t+κ(a_t−q_t)`，令 `q_{t+1}=q*` 得 `a_t=q_t+κ^{-1}(q*−q_t)`。`κ=0.295 ⇒ κ^{-1}≈3.39`，即指令需领先目标约 3.4 步；时间常数 `−τ/ln(1−κ)≈0.095 s`。⇒ 任何"零延迟"叙事都必须先扣掉这 3 步。∎

**引理 L15（预算最优分配）** 设总预算 `L_max`，快/慢两路频率为 `f_f=1/τ`、`f_s=1/(kτ)`，失败代价对接触相位状态发散率 `λ_c` 敏感。最小化期望误差的拉格朗日解给出：在 `λ_c` 高的相位（insert/align）把预算向快路倾斜；在 `λ_c` 低的相位（transport）向慢路/chunk 倾斜。⇒ "按相位分配延迟"是可证明的策略，不是启发式。∎

**引理 L16（多 LoRA 干扰界）** 若两个增量作用于同一线性层且其列空间重叠度为 `c=‖B_1^⊤B_2‖/(‖B_1‖‖B_2‖)`，则合并误差 `‖(W+Δ_1+Δ_2)x−(W+Δ_1)x‖ ≤ c‖Δ_2x‖` 量级。⇒ 一次只激活一个增量、或对 `B_k` 做正交化，可把干扰压到可忽略。∎

## 5. 算法骨架

```python
# ===== UniBot-LoRAC：慢策略 + 合并路由 + 反射 + 证书（单 API）=====
class UniBotLoRAC:
    def __init__(self, ckpt, L_max_ms=105, tau=1/30):
        self.base, self.bank = load_one_checkpoint(ckpt)   # base + adapter bank（同一文件）
        self.regime = RegimeClassifier()                    # U21
        self.reflex = ReflexCorrect()                       # U18, <=3ms
        self.lead   = ServoLead(kappa=0.295)                # U20
        self.ledger = LatencyLedger()                       # U23
        self.sched  = ChunkScheduler()                      # U13/U19
        self.sessions = {}                                  # 端口隔离

    def reset(self, port=None):
        s = self.sessions.setdefault(port, Session()); s.reset()
        # 形态-2：episode 开始预合并任务增量（代价藏在 reset 内）
        z = s.task_token
        self.bank.prefetch_and_pin(z, s)

    def get_action(self, obs, port=None):
        s = self.sessions[port]; t0 = now()
        Zr = self.regime.predict(obs)                       # U21（低维 regime）
        k_target = self.sched.depth(Zr)                     # 相位自适应开环深度
        Ta = max(1, k_target)

        # --- 慢策略：块边界切换/合并 LoRA（trunk 低秩服务，动作头真合并）---
        if s.dirty_adapter(Zr):
            self.bank.activate(Zr)                          # 指针切换 O(1)
            self.bank.merge_into_action_head(Zr)            # 小块合并，双缓冲
        a_chunk = self.base.act(obs, Ta)                    # 慢 VLA 出块

        # --- 快反射：事件触发 + 不确定度门控（U18/U19/U24）---
        if self.sched.event(obs, s):
            da, u = self.reflex(obs, s.last_action)
            if u < TAU_U and norm(da) > TAU_D:
                a_chunk = clip_residual(a_chunk + da[:Ta], DELTA_MAX)

        # --- 伺服超前 + 缝合（U14/U20 + 第1轮 U7）---
        a_chunk = self.lead.compensate(a_chunk, obs)
        a_chunk = stitch(a_chunk, s.last_action)

        L = (now() - t0) * 1000
        self.ledger.record(L, k=ceil(L/ (tau*1000)), Ta=Ta, Zr=Zr)  # U23
        s.last_action = a_chunk[-1]
        return pack(a_chunk)                                 # 单 API、单权重

# ===== LoRA 库：trunk 不合并（低秩服务），动作头真合并 =====
class LoRABank:
    def activate(self, Zr):
        self.active = Zr
    def merge_into_action_head(self, Zr):
        # W_head' = W_head + B_{Zr} A_{Zr}，写入 shadow，原子交换
        B, A = self.bank[Zr]
        self.head_shadow = self.head_base + B @ A
        swap_atomic(self.head, self.head_shadow)

# ===== 反射器：本体 + 腕部小图；输出残差与不确定度 =====
class ReflexCorrect:
    def __call__(self, obs, a_prev):
        w = downscale(obs["observation.images.cam_left_wrist"][-1],
                      obs["observation.images.cam_right_wrist"][-1])  # 64x64
        f = torch.cat([enc(w), obs["observation.state.left_arm"],
                       obs["observation.state.right_arm"],
                       obs["observation.state.left_gripper"],
                       obs["observation.state.right_gripper"],
                       a_prev])
        mu, logvar = self.net(f)
        return mu, torch.exp(0.5*logvar)                    # (δa, u)

# ===== 伺服超前（U20）：只超前均值，不放大噪声 =====
class ServoLead:
    def __init__(self, kappa): self.kappa = kappa
    def compensate(self, a, obs):
        q = obs_state(obs)
        return q + (a - q) / self.kappa                     # κ^-1 ≈ 3.39
```

## 6. 延迟预算与成本模型（工程可行性）

**预算表（目标，真机需实测校正）**：

| 段 | 目标 p50 | 目标 p99 | 备注 |
|---|---|---|---|
| obs 编码 + 传输 | ≤8 ms | ≤15 ms | 4 路相机降分辨率（第 1 轮已设 240×320） |
| 主干 VLA | ≤60 ms | ≤80 ms | 参考 UnifoLM-WLA 报告 <105 ms 量级 |
| 动作头（含 LoRA 合并摊销） | ≤6 ms | ≤10 ms | 合并只在块边界，小矩阵 |
| 反射器 | ≤2 ms | ≤3 ms | 仅事件窗口内启用 |
| 缝合 + 限幅 + 记账 | ≤1 ms | ≤2 ms | O(1) |
| **合计** | **≤77 ms** | **≤110 ms** | 开环深度 `k≈3–4` |

**LoRA 成本（示例：`d=3072, L=32`，每层 7 个线性层，`r=8`）**：
- 参数量 `≈ 14·r·d·L ≈ 11.0 M`（fp16 约 22 MB）；
- trunk 低秩服务每 token 额外算力比例 `≈ 4r/d ≈ 1.0%`；
- 动作头合并 MACs 远小于主干（动作头参数量小 1–2 个数量级），毫秒级，可完全藏进 chunk 执行；
- **结论**：不需要"整模型双缓冲"（显存代价过大）；用"trunk 低秩服务 + 动作头合并"即可同时拿到合规、低延迟与低内存。

## 9. 本地数据核查（可复算）

**数据**：`exp/duo_rows_cache/*.json`，文件名形如 `{Task}_{offset}.json`；每个文件是一页 LeRobot 行（`rows[*].row`），含完整的 `observation.state.*` 与 `action.*`。
- 覆盖 15 个任务：ArrangePlates / ArrangeTestTubes / ColorArrangement / ConveyorSorting / DisconnectEthernet / FoldTowel / FruitCollection / HangCup / OrganizeBookshelf / PlugCharger / PlugInEthernet / PourOutMedicine / SyringeWaterTransfer / Unlock / ZipUp。
- 每任务 30 页（offset 0,100,…,2900），每页 100 帧 ⇒ 每任务 3000 帧。
- 动作向量取 `[left_arm(7), right_arm(7), left_gripper(1), right_gripper(1)]`（16 维）。

**计算口径**：
1. `dt = diff(timestamp)`；取页内相邻帧，跨页边界（episode 重置）剔除。中位 `dt=0.03333 s`。
2. 一阶伺服：以 `q=observation.state.{left,right}_arm` 为状态、`a=action.{left,right}_arm` 为指令，回归 `Δq_t` 对 `(a_t−q_t)` 得 `κ` 与相关系数。
3. 秩：对页内动作增量 `Δa` 做 PCA，报告累计方差达 50/80/90/95% 所需维数（16 维空间）。
4. 任务均值偏移秩：对 15 个任务的动作均值（去全局均值）做 PCA。
5. Fisher 比：任务间均值方差 / 任务内方差。
6. 开环误差：用"线性外推" `Ŝ_k: a_{t+k} ≈ a_t + k(a_t−a_{t−1})`，RMSE 除以页内动作标准差 `σ`。
7. 反射增益：特征 `[a_t, a_t−a_{t−1}, a_{t−1}−a_{t−2}, q_t, a_{t−2}]`，线性最小二乘，按页奇偶做训练/测试切分；比较"线性外推"与"反射"的测试 RMSE。
8. 榜单：`exp/unibot_leaderboard_20261102.json`，8 模型 × 32 任务的 success_rate 矩阵；`oracle=每列取最大后求均值`；中心化后做 SVD。

**主要结果**：
- `κ=0.295`，`corr=0.729`；`τ_c≈0.095 s`。
- 动作增量维数：全局 90% → 4；各任务 90% → 2–5。
- 任务均值偏移：80% → 2，90% → 4，95% → 5。
- Fisher `B/W=0.078`（任务解释 ~7.2% 动作方差）。
- 开环误差 `e(k)/σ`：1→0.068，4→0.279，8→0.647，16→1.45。
- 反射改善：h=1→12.7%，4→20.0%，8→27.4%，16→41.3%。
- 大修正稀疏：`|Δa|>0.5` 占 1.69%，`>1.0` 占 0.08%，p99=0.533。
- 自相关：动作 lag-1=0.9995，增量 lag-1=0.792。
- 榜单：best single 29.70，oracle 33.96，top-2 32.22；中心化 SVD 90% 需 7/8 维。

> **重要保留**：以上是**离线日志统计**，不是真机结论；`e(k)` 的绝对尺度会随策略与控制器不同而漂移，本报告只把**形状与相对改善**作为设计依据，绝对阈值一律以 E619/E620 的真机校准为准。
