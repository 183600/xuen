### 第 6 轮灵感驱动研究记录

**灵感词**：工具调用、移动底盘

**继承关系**：第 5 轮 CADVS-v5（IP-493~496）把提议机制升级为「认证的生成式执行」（CGE）：条件流匹配提议 π_θ^FM、嵌入记忆与固化 LMEM-v2、面部情感调制 FAMK，并用定理 6（证书不变性）证明「换提议不换门」。执行集嵌套 Exec_CADVS-v5 ⊆ Exec_CADVS-v4 ⊆ … ⊆ Exec_v29。本轮不推翻 v5，而是补 v5 两个一直被视为「环境假设」而非「被认证对象」的前提：(a) **单一技能闭环假设**——v5 每次只对一个候选轨迹铸证，默认「一个任务 = 一次铸证」，但真实具身系统由规划器调用**工具库**（抓取/开门/插孔/导航）组合成长程计划，单轨迹证书无法直接保证**工具组合**的安全；(b) **固定底盘假设**——v5 的 EEK 可达性、BCK 支撑多边形、3DCF 覆盖都写在固定基座的世界系里，移动底盘让基座成为可主动选择的自由度，「先移到哪、再做什么」本身成为影响可认证性的决策。两个灵感词统一为主题「认证的工具调用式移动执行」（Certified Tool-Calling Mobile Execution, CTME），形成 CADVS-v6（IP-501~505）。本轮自律：**硬门数量仍不增**（维持七门），工具调用与移动底盘都作为「门之上的编译/组合/运行时层」处理，不引入新锚；执行集升级为 Exec_CADVS-v6 ⊆ Exec_CADVS-v5。

**直觉与动机**：

1. **工具调用 → 工具不是黑盒 API，而是「带证书契约的技能」**。直觉上，LLM 规划器输出 `pick(obj)`、`open(drawer)` 这类调用，语法正确不等于语义安全：单位错、参数越界、前置条件不满足（物体太远/被遮挡/超重）都会让一个「合法调用」执行出危险动作。更隐蔽的是**证书洗白（certificate laundering）**：工具 A 单独认证、工具 B 单独认证，但 A 的实际终态与 B 的前置假设之间有残差，串联后整体不安全。形式化上引入**认证工具契约 CTC**：每个工具 τ 携带 C_τ=(Pre, Post, Inv, Cert, Res, Fail)——前置谓词、效果关系、过程不变式、所保证的门证书与余量、资源包络（时间/工作空间/力/基座位移）、失败模式与回退。规划器只被允许在**类型化工具 DSL** 上产出调用；编译器做类型/单位/前置条件检查，证不出前置即 fail-closed 拒绝。工具因此从「不可信黑盒」变成「可静态检查、可运行时监控、可组合推理」的契约对象。

2. **移动底盘 → 基座位姿是可搜索的「移动工具」，把可达性/稳定性/定位折进既有门**。直觉上，机械臂够不到时人会「挪一步再伸手」；移动底盘让这件事可计算：对每个操作目标 p，存在一个可行基座集合 B_adm(p)，在其中选一个 b* 使末端可达余量、整机稳定余量、定位置信都满足。形式化上把「移动」本身建模为工具 MOB(b_target)，其契约保证基座安全到达；操作工具调用前由**移动可行性证书 MFC** 求解 b*。关键设计：移动不新增硬门，而是把基座位姿当作**决策变量**去满足 v5 的 EEK（可达）、BCK（稳定）、3DCF（覆盖/定位）；B_adm 为空则目标不可调用（fail-closed）。这既回答了「移动底盘如何进入认证框架」，又保持 Exec_v6 ⊆ Exec_v5：移动只在已认证配置中挑选，不放松任何门。

3. **工具调用 + 移动 → 组合安全必须靠「调用边界重认证」而不是「单工具认证之和」**。直觉上，长程计划的风险集中在**交接点**：工具切换瞬间物体可能滑移、基座可能漂移、夹爪力可能未归零。单工具证书只在各自域内成立，跨域边界无人负责。形式化上引入**组合证书核 CCK**：每次调用结束在观测状态 s_i 上重认证，计算与预测终态 Post 的残差 r_i，并用**余量传递引理**把 r_i 折算成门的余量消耗；若 m_i < L·r_i 则交接不成立，必须重规划或回退。定理 10（组合归纳）证明：在「初态认证 + 每工具可靠 + 前置被前序后置蕴含 + 交接残差被余量支配 + 不变式保持」下，整条工具序列 ∈ Exec_v6；反例说明去掉交接重认证时，两个各自安全的工具可因基座漂移组合出越界。这把「工具调用」从语言层的能力问题，变成可证明的组合安全问题。

**关键洞见**：v5 回答「提议=任意生成器时证书边界是否不变」；v6 回答「当执行由不可信规划器发起的工具序列组成、且基座可主动移动时，证书如何跨越调用边界与移动自由度保持可靠」。答案是把工具契约化（CTC）、把移动折进门（MFC）、把组合安全落在调用边界（CCK），再用运行时监控 TCM 兜住契约执行偏差。七硬门记号 kc_evidence_forged_v5 原样复用；新增的只有契约层、交接余量、基座位姿搜索与运行时一致性监控。Exec_v6 ⊆ Exec_v5 由「只调用已认证工具 + 只在 B_adm 选基座 + 每边界重认证」三重保证。

**形式化目标（增量）**：
1. 工具契约 C_τ=(Pre, Post, Inv, Cert, Res, Fail)；类型化工具 DSL 与静态检查器 Compile(plan, s_0) → 接受/拒绝。
2. 交接证书 H_i=(r_i, Δm_i, fresh_i)；余量传递 m_i ≥ L·r_i；组合归纳定理。
3. 移动可行性 MFC：B_adm(p)={b∈B_trav : ρ_reach(b,p)≥ρ*_r ∧ ρ_bal(b)≥ρ*_b ∧ U_δ(b)⊆安全}；基座搜索 + MOB 工具契约。
4. 运行时一致性监控 TCM：过程不变式 Inv 与资源包络 Res 的在线检查，违规 → 中止/保持/回滚。
5. 定理 9（契约可靠性）、定理 10（组合归纳）、定理 11（移动折叠/退化）、定理 12（监控可靠性）、定理 13（七锚完备性保持）。
6. Exec_CADVS-v6 = {c_{1:n} : ∀i 调用已认证 ∧ Pre 被前序后置+交接蕴含 ∧ b_i∈B_adm ∧ 边界重认证} ⊆ Exec_CADVS-v5。

**本轮最大风险**：**工具契约的规格缺口**——整条认证链的可靠性都押在「C_τ 已把该工具全部安全谓词与失效模式写全」这一信任基上；单个工具可被认证，但跨工具的涌现危害、以及根本没写进契约的失效模式，无法被任何在线重认证或监控捕获，证书可能「对错误规格严格成立」，而系统对此无法自证。

## 2. 关键算法骨架

### IP-501 CTCK：认证工具契约核（离线注册 + 准入时静态编译，O(1)/O(|plan|)）

```python
@dataclass(frozen=True)
class ToolContract:
    """工具契约六元组。契约是信任基：门谓词必须写全，否则定理 9 不成立。"""
    tool_id: str
    version: str
    pre:  Callable[[State, Args], bool]        # 前置谓词
    post: Callable[[State, State, Args], bool] # 效果关系
    inv:  Callable[[State], bool]              # 过程不变式
    cert: GateCertificateTemplate              # 保证的门与余量模板
    res:  ResourceEnvelope                     # T_max, W, F_max, db_max, E_max
    fail: FailPolicy                           # ABORT / HOLD / ROLLBACK / RETRY
    units: dict[str, str]                      # 参数单位，供量纲分析

@dataclass
class CertifiedToolContractKernel:
    """CTCK：类型化工具 DSL 的静态编译器。
    红线：规划器（含 LLM）不可信，只提交调用；认证权在门与契约，不在规划器。"""
    registry: dict[str, ToolContract]
    gate_templates: dict[str, GateCertificateTemplate]

    def compile(self, plan: Plan, s0: State) -> CompileResult:
        # 1) 工具存在性 + 版本锁定：未知/未认证/版本不符 → reject
        # 2) 类型/量纲检查：unit_dim(args) 必须与 C_τ.units 一致，否则 reject
        # 3) 符号执行：从 s0 沿 Post 传播符号状态，逐调用检查 Pre 可证
        #    （可证性 = 在保守区间/线性松弛下蕴含；证不出 → reject，fail-closed）
        # 4) 安全关键参数（速度/力/步长）不得来自自由文本，必须落在 Res 包络内
        # 5) 契约版本 + 门证书模板一致性（防止旧契约引用已废弃门）
        sym = symbolic_state(s0)
        for i, call in enumerate(plan.calls):
            tau = self.registry.get(call.tool_id)
            if tau is None or not version_ok(tau, call):
                return CompileResult(False, f'UNKNOWN_TOOL@{i}')
            if not units_match(call.args, tau.units):
                return CompileResult(False, f'UNIT_MISMATCH@{i}')
            if not within_envelope(call.args, tau.res):
                return CompileResult(False, f'ARG_OUT_OF_ENVELOPE@{i}')
            if not prove(sym, tau.pre, call.args):
                return CompileResult(False, f'PRECONDITION_UNPROVABLE@{i}')
            sym = apply_post(sym, tau.post, call.args)
        return CompileResult(True, 'COMPILED', symbolic_obligations=sym)
```

### IP-502 CCK：组合证书核（每次调用边界，O(1) 门重评 + O(|G|) 余量折算）

```python
@dataclass
class CompositionalCertificateKernel:
    """CCK：调用边界重认证 + 余量传递。定理 10：单工具认证之和 ≠ 组合安全。"""
    lipschitz: dict[str, float]        # 各门谓词对状态的 Lipschitz 常数 L_g

    def handoff(self, i: int, s_prev: State, s_now: State,
                tau: ToolContract, args: Args) -> HandoffResult:
        r = state_residual(s_now, tau.post(s_prev, s_prev, args))  # 预测 vs 实测
        dm = {g: L_g * r for g, L_g in self.lipschitz.items()}      # 引理 45
        margins = {g: gate_margin(s_now, g) for g in GATES}         # v5 七门余量
        ok = all(margins[g] >= dm[g] for g in GATES) and fresh(s_now)
        return HandoffResult(r=r, delta_margin=dm, margins=margins,
                             certified=ok)

    def compose(self, plan: Plan, trace: Trace, s0: State) -> ComposeResult:
        # 归纳基：s0 已在 Exec_v5（由 v5 铸证或人工初始化）
        if not in_exec_v5(s0):
            return ComposeResult(False, 'BASE_NOT_CERTIFIED')
        s = s0
        for i, call in enumerate(plan.calls):
            tau = self.registry[call.tool_id]
            s_new = trace.observed_state_after(i)
            # 前置必须由「前序后置 + 交接残差」蕴含，而非假设
            if not implies_post_plus_residual(s, tau, call.args):
                return ComposeResult(False, f'PRE_NOT_ESTABLISHED@{i}')
            H = self.handoff(i, s, s_new, tau, call.args)
            if not H.certified:
                return ComposeResult(False, f'HANDOFF_REJECTED@{i}', H)
            s = s_new
        return ComposeResult(True, 'COMPOSED_CERTIFIED')
```

```python
@dataclass
class ToolCallConformanceMonitor:
    """TCM：只检查契约声明过的 Inv/Res。
    定理 12：可检测违规在 τ_s + T_react 内进入 fail-closed；
    诚实边界：契约没声明的危害、低于传感器噪声的偏移，监控原理性看不见。"""
    rate_hz: float = 1000.0

    def step(self, s: State, tau: ToolContract,
             elapsed: float, used: ResourceUsage) -> MonitorVerdict:
        if not tau.inv(s):                       return MonitorVerdict.ABORT
        if elapsed > tau.res.T_max:              return MonitorVerdict.ABORT
        if used.force > tau.res.F_max:           return MonitorVerdict.ABORT
        if used.energy > tau.res.E_max:          return MonitorVerdict.ABORT
        if used.base_disp > tau.res.db_max:      return MonitorVerdict.ABORT
        if not inside_workspace(s, tau.res.W):   return MonitorVerdict.ABORT
        return MonitorVerdict.OK

    def on_violation(self, tau: ToolContract, snapshot: CertifiedSnapshot):
        # 按 Fail_τ 执行 HOLD/ROLLBACK；回滚目标只允许是「已认证快照」
        return tau.fail.action(snapshot)
```

### IP-505 EFA-v6：契约编译 + 边界重认证 + 移动折叠 + 监控

```python
@dataclass
class EvidenceForgingAssemblerV6:
    """EFA-v6：七硬门不变，工具调用/移动均为门之上的层。"""
    ctck: CertifiedToolContractKernel
    cck:  CompositionalCertificateKernel
    mtk:  MobilityAsToolKernel
    tcm:  ToolCallConformanceMonitor
    v5:   EvidenceForgingAssemblerV5        # 工具内铸证仍复用 v5

    def run(self, plan: Plan, s0: State, context: Context) -> RunResult:
        comp = self.ctck.compile(plan, s0)
        if not comp.ok:
            return RunResult(False, 'PLAN_REJECTED', comp.reason)  # fail-closed
        s = s0
        for i, call in enumerate(plan.calls):
            tau = self.ctck.registry[call.tool_id]
            # 1) 若目标需挪基座：先选 b* 并调用移动工具
            if call.requires_base_move:
                bases = self.mtk.admissible_bases(call.target, s)
                if not bases:
                    return RunResult(False, 'NO_ADMISSIBLE_BASE', i)  # 不可调用
                b_star = self.mtk.pick(bases, call, s)
                ok, s = self._exec_tool(self.mtk.mobility_tool(b_star), s, context)
                if not ok:
                    return RunResult(False, 'MOBILITY_FAILED', i)
            # 2) 工具内：v5 流提议 + 七门铸证 + TCM 在线监控
            ok, s_new = self._exec_tool(tau, s, context)
            if not ok:
                return RunResult(False, 'TOOL_FAILED', i)
            # 3) 调用边界：CCK 重认证（余量传递），不通过则整链拒绝
            H = self.cck.handoff(i, s, s_new, tau, call.args)
            if not H.certified:
                return RunResult(False, 'HANDOFF_REJECTED', i, H)
            s = s_new
        return RunResult(True, 'CERTIFIED_TOOL_CHAIN')

    def ecs_v6(self, base_ecs_v5: float, eta_tool: float, eta_mob: float) -> float:
        # 软评分只影响候选排序，不改变任何硬门
        return base_ecs_v5 * eta_tool * eta_mob
```

## 4. 正确性论证（增量更新）

### 引理 45（交接余量传递）

**陈述**：设门谓词 kc_g 关于状态 s 是 L_g-Lipschitz 的，预测终态 ŝ_i 满足门余量 m_g(ŝ_i)≥0；实际终态 s_i 满足 ‖s_i−ŝ_i‖≤r_i。则实际余量 m_g(s_i) ≥ m_g(ŝ_i) − L_g·r_i。故当 m_g(ŝ_i) ≥ L_g·r_i 时，实际终态仍通过门 g。

**证明**：由 Lipschitz 性 |m_g(s_i)−m_g(ŝ_i)| ≤ L_g‖s_i−ŝ_i‖ ≤ L_g·r_i；移项即得。∎

### 引理 46（可达/稳定集合的单调性）

**陈述**：B_adm(p) 关于阈值 ρ*_r、ρ*_b 单调不增：若 ρ*_r↑ 或 ρ*_b↑，则 B_adm 只可能缩小；关于目标可达性 p 不保证单调（存在基座布置的局部性）。故 MTK 只能收紧、不能凭空扩大可调用目标集。

**证明**：B_adm 是若干「余量 ≥ 阈值」谓词的交集；提高任一阈值只会删去元素。∎

### 引理 47（静态检查的保守可靠性）

**陈述**：CTCK.compile 是**可靠但不完备**的：若它接受 plan，则每条 Pre 在保守符号域内可证；但它可能拒绝实际安全的 plan（符号域不精确）。由于拒绝是 fail-closed，不完备只损失可用性，不损失安全性。

**证明**：接受蕴含「保守域内前置可证」；保守域 ⊇ 实际可达状态集，故接受时前置在真实执行中成立。不完备来自保守近似（区间/线性松弛）的过近似。∎

### 引理 48（监控检测延迟界）

**陈述**：设 TCM 采样周期 τ_s=1/rate，传感器误差 ≤ ε_m。若违规偏移在可检测域内（偏离契约界 > ε_m）且持续 ≥ τ_s，则监控在 τ_s + T_react 内检出并进入 fail-closed（HOLD/ROLLBACK）。

**证明**：首次越过「契约界 + ε_m」的采样点必落在违规发生后的一个 τ_s 内；检出后执行 Fail_τ 动作耗时 ≤ T_react。∎

### 定理 9（工具契约可靠性）

**陈述**：若工具 τ 在其域 Dom_τ={s: Pre_τ(s,args) ∧ Res_τ 被遵守} 上执行产生的轨迹 x_τ 满足 Cert_τ，且 Cert_τ 蕴含 v5 七门谓词，则任何通过 CTCK 类型/前置检查且成功执行的调用都给出 x_τ ∈ Exec_CADVS-v5。**诚实边界**：若 Cert_τ 漏写某安全谓词（规格缺口），则定理前提不成立，在线机制无法补救。

**证明**：由 Cert_τ ⇒ 七门谓词，且 x_τ 在 Dom_τ 内执行满足 Res_τ；直接得 x_τ∈Exec_v5。∎

### 定理 10（组合归纳 / 组合安全）

**陈述**：在以下条件下，整条工具序列的拼接轨迹属于 Exec_CADVS-v6 ⊆ Exec_CADVS-v5：
(C1) 初态 s_0 ∈ Exec_v5；
(C2) 每个 τ_i 满足定理 9；
(C3) 每次调用的 Pre_{τ_i}(s_{i-1}) 由「前序 Post_{τ_{i-1}} + 交接残差 r_{i-1}」蕴含；
(C4) 交接余量支配：m_g(s_i) ≥ L_g·r_i 对所有门 g（引理 45）；
(C5) 过程不变式 Inv_{τ_i} 在 TCM 下全程保持。
**证明**：对 i 归纳。基：C1。步：设 s_{i-1}∈Exec_v5 且后置成立；由 C3 前置成立、C2 得调用轨迹∈Exec_v5 且后置成立；由 C4 交接后 s_i 仍在 Exec_v5；C5 保证过程不越界。故全部 i 成立，拼接轨迹∈Exec_v6。∎

**反例（无 C4 时组合失败）**：工具 A=reach-and-grasp 在固定基座下保证 EEK 余量 m_EE=0.06；工具 B=place 假设物体仍在夹爪系 p_g。A 与 B 之间基座因轮地打滑漂移 δ=0.08 m，实际 EEK 余量降为 −0.02；两张单工具证书仍写「通过」，整体已越界。C4 的交接重认证恰好在边界捕获该残差并拒绝整链。

### 定理 11（移动折叠与退化）

**陈述**：(i) 若规划器只从 B_adm(p) 选基座且 MOB 契约可靠，则移动不放松任何门，Exec_CADVS-v6 ⊆ Exec_CADVS-v5；(ii) 若禁用移动（B_trav={b_0}），则 MTK 退化为恒等，EFA-v6 精确退化为 v5（工具调用层对单工具亦退化为 v5 铸证）；(iii) 扩大 B_adm 至多扩大「可调用目标集」，不会使任何越界轨迹进入 Exec_v6。

**证明**：(i) 基座位姿是决策变量，所有门仍在最终配置上求值；选基座只是在已认证配置中搜索。(ii) 固定基座时 B_adm⊆{b_0}，MOB 为空操作，CCK 在单工具边界退化为 v5 的终态检查。(iii) 由引理 46，B_adm 收缩只减不增；门谓词本身未被修改。∎

### 定理 12（运行时监控可靠性）

**陈述**：在引理 48 的条件下，任何**契约可检测**的违规都在 τ_s+T_react 内进入 fail-closed，故不存在「契约可检测违规的未认证持续执行」。**诚实边界**：契约未声明的危害、以及幅度低于传感器噪声的偏移，监控原理性不可见，不在此定理覆盖范围。

**证明**：由引理 48 的检测延迟界；检出后 Fail_τ 保证执行离开「违规持续」状态。不可见部分不在可检测域内，故不计入。∎

### 定理 13（七锚完备性保持）

**陈述**：v6 不增删锚点：七锚 {3DCF, MSRG, HICK, EEK, LTEM, VACK, BCK} 的完备性（v4 定理 4）保持。CTCK/CCK/TCM 是门之上的编译/组合/监控层，MTK 把移动折进 EEK/BCK/3DCF；工具内提议仍是 FMPP，均非新锚。

**证明**：锚点集合不变；新增层不修改门谓词，只决定「调用哪个已认证工具、在哪个已认证基座位姿执行、边界是否重认证」。由定理 11 的折叠与定理 9/10 的可靠性，覆盖链只强不弱。∎

### 定理 v6（组合认证总装）

**陈述**：在 v5 假设 (B1)~(B7) 与新增 (B8) 工具契约 Cert_τ 可靠（无规格缺口）、(B9) 交接残差可测且 r_i≤r_max 下：
(i) Exec_CADVS-v6 ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29；
(ii) 组合归纳成立（定理 10），单工具认证之和不足以替代边界重认证；
(iii) 移动折叠成立（定理 11），固定基座精确退化 v5；
(iv) 可检测违规在 τ_s+T_react 内 fail-closed（定理 12）；
(v) 七锚完备性保持（定理 13）。
**证明**：(i) 由定理 9/10/11 的逐调用与逐边界保证。(ii)~(v) 分别由定理 10、11、12、13。∎

**诚实声明**：(B8) 是整条链的信任基，无法由系统自证——契约由人/工具作者撰写，漏写谓词即产生「对错误规格严格成立」的证书；(B9) 残差依赖可观测量与传感器一致性，弱纹理/遮挡下 r_i 可能被低估；工具组合的涌现危害若不在任何单一契约中声明，定理 10 的 C3/C4 无法覆盖；LLM 规划器虽被限制在类型化 DSL 与包络内，仍可能通过**语义合法但意图错误**的调用序列（如反复开关、无意义长链）消耗资源，需上层任务合理性检查。

## 7. 本轮最大风险（最终确认）

**一句话**：**工具契约的规格缺口**——整条认证链的可靠性都押在「C_τ 已把该工具全部安全谓词与失效模式写全」这一信任基上；单个工具可被认证，但跨工具的涌现危害、以及根本没写进契约的失效模式，无法被任何在线重认证或监控捕获，证书可能「对错误规格严格成立」，而系统对此无法自证。
