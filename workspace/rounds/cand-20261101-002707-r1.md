# 第 13 轮 · SCENE-TURN：把「单轮指令 → 动作」改成「与场景的多轮对话」，用场景账本、视觉指认和反事实绑定审计补上“动哪个/动到哪/动完没有”

> 检索/复核日期：**2026-11-01（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新一轮灵感循环的第 1 轮，但在状态文件里接在第 12 轮 CHUNK-SERVO 之后，因此编号写作第 13 轮，避免覆盖历史。三个灵感词是「**多轮对话 / 场景理解 / 可解释性**」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是在它们之上补一层：**CHUNK-SERVO 解决最后 3 厘米怎么动；SCENE-TURN 解决最后 3 厘米之前的“动哪个、动到哪、按什么顺序、动完没有”。**

## 0. 先给结论：榜首不到 30%，但真正的共享瓶颈不只是控制，而是 binding

截至 2026-11-01，官网首页/榜单静态文案仍显示“即将发布 Coming Soon”，而 `leaderboard_data.json` 里已有 8 个模型：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。这份榜单仍是**预览/合成信号**：`generated_from=gen_leaderboard.py`，`step~success` 回归 R²≈0.9999996–0.9999999，详情页视频全是占位，232/256 个任务成功率不是 10% 的整数倍。它不能当 SOTA、难度表或失败分布。

但榜单之外，官方任务描述和公开证据指向一个更具体的结论：

> **32 个任务里有 20+ 个不是“看到一个物体就抓”，而是“把指令里的指代、颜色、顺序、空间关系、嵌套关系绑定到当前场景”。** 5 类泛化轴——位置、干扰物、背景、未见物品、人为干扰——本质上都是 binding 轴：物体动了，绑定要跟着变；干扰物来了，绑定要排除它；背景变了，绑定不能靠背景记忆；未见物品来了，绑定要泛化；人把物体拿走了，绑定要重绑。

所以本轮押注 **SCENE-TURN**：

> 用官方 WLA 的同一套 VLM 做**内部多轮对话**的 planner；用确定性几何、颜色、模板和演示先验做**场景账本**（Scene Ledger）；用**角色感知的视觉指认**把目标/受器直接画给 VLA 看；用**反事实绑定审计**（mask 目标/受器/干扰物、替换指令中的目标词）判断模型到底在看谁；审计不过就重绑、重规划或退回 VLA。所有轮次都是内部的、结构化的、1–3 次/ episode，**不是人类对话，也不是第二个模型**。

三个可验证创新点：

1. **Scene Ledger**：任务条件化的场景账本，不是通用 scene graph；每个物体有 id、类别、颜色、3D 位置、支撑/包含关系、角色、置信度、最后可见时间；粗到 1–2cm 即可，精细对齐交给 CHUNK-SERVO。
2. **Internal Multi-turn Protocol**：把“多轮对话”重新解释为 **ASK → GROUND → CHECK → REVISE** 的内部子目标协议；对话的另一端是场景账本，不是人；每 episode 1–3 次 VLM 调用，不是每步。
3. **Binding Audit**：对目标/受器/干扰物/背景做反事实 ROI mask，对指令做目标词替换，定义 binding margin；margin 低就触发视觉重指认或确定性回退。这是“可解释性”落到控制环的方式，不是事后画热力图。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **多轮对话** | 内部结构化协议：ASK/GROUND/CHECK/REVISE；每轮是 JSON，不是自由文本；在子目标边界触发 | 不做人类语音/聊天；API 没有对话通道；不做每步 VLM 调用 |
| **场景理解** | 任务条件化 Scene Ledger：物体、颜色、3D 位置、左右/上下/包含关系、顺序、角色、置信度 | 不做通用 3D 场景图大模型；不做第二个学习检测器；不靠 scene graph 文本硬灌 |
| **可解释性** | Binding Certificate：目标 id、mask 前后动作差、语言反事实差、binding margin、置信度；日志可回放 | 不做事后注意力热图；不做与动作无关的“解释” |

## 1. 本轮新核实的事实（只列会改变方案的）

### 1.1 榜单仍是预览，不能拿来选任务

8 个模型、32 维任务成功率的取证与第 12 轮一致：

- `leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`；对 8 个模型 ×32 任务做 `step_score ~ success_rate` 回归，**R²≈0.9999996–0.9999999，最大残差 <0.006**。
- 8 个模型的 32 维任务成功率两两相关，**平均 off-diagonal 相关系数约 0.0975**；真实任务难度应让不同模型正相关。
- 每任务只有 10 次 trial，但成功率出现 27.29%、27.85%、38.43% 等非 10% 整数倍；真实 10 次只能是 0/10、…、10/10。
- 详情页 32 个任务视频仍是“测试视频占位，后续可替换为真实视频文件”。

**结论**：不从榜单任务排名里挖创新点；只从官方任务描述、公开数据、WLA 文档和公开论文里挖。

这解释了为什么“更大的 VLA”不一定涨点：模型可以学会抓取 primitive，但在干扰物、顺序、颜色、关系上把指令绑错，最后一步就是 0 分。公开研究把这种现象叫 **binding / grounding failure**，不是 control failure。

### 1.3 API 没有人类对话通道：多轮对话只能是对场景的内部协议

提交 README（2026-11-01 复核）明确：

- `observation.language` 是**单个 `str`，episode 内不变，没有时间轴**；没有音频、没有文本输入、没有人类在环通道。
- `get_action(obs)` 每次返回一个 action chunk；chunk 内 evaluator 不再调用模型，也没有打断机制。
- 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分。
- `action.pivot [7]` 是“Lower-body / pivot target”，没有逐维语义；`control_space` 只能是 `joint` 或 `ee`。

**关键推论**：

1. 不能做“问人—人回答—再动”的对话；本轮把“多轮”解释为**模型与场景账本之间的内部对话**。对话的另一端是确定性几何/场景状态，不是人类。
2. 不能每步调用 VLM；VLM 调用必须放在子目标边界，并且异步，不能阻塞 `get_action`，否则延迟会抖。
3. 不能依赖 chunk 内的新观测；子目标验证只能在 chunk 边界做。

### 1.4 数据与标定：腕部内参已提供，头相机外参和 pivot 近恒定

32 个 HF 数据集（collection 的 `lerobot.totalEpisodes` 与 `numRows`，2026-11-01 复核）合计：

| 项 | 数值 |
|---|---:|
| episodes | **33,276** |
| frames | **18,282,246** |
| 时长 | **169.28 h**（30 fps） |
| 任务数 | 32 |
| 单任务 episodes | 969–1,533 |
| 单任务平均时长 | 6.2 s（HangCup）–37.6 s（ToolboxStorage） |

关键更正与新发现：

- **腕部相机内参已提供**：当前 `meta/info.json` 有 `camera_params.wrist_left.color.camera_matrix` 与 `dist_coeffs`，wrist_right 同；HangCup 示例 `fx≈436.4, fy≈435.9, cx≈323.9, cy≈242.9`。第 12 轮“腕部没有内参”的说法已过时，必须修正。仍需验证的是**手眼外参/腕部安装误差**，不是内参。
- **头相机外参近恒定**：`state_d435` 在 HangCup 前 100 帧的均值 `[0.1301, 0.0178, 0.4565, -0.0070, 1.0114, -0.0159]`，标准差 `[0.0003, 0.0016, 0.0001, 0.0029, 0.0005, 0.0073]`；跨 4 个采样段（400 帧）标准差约 `[5.5mm, 3.0mm, 1.6mm, 0.0105rad, 0.0130rad, 0.0130rad]`。跨任务均值在 x 0.106–0.138、z 0.454–0.470、pitch 0.882–1.031 之间。**结论：可以按任务取一个常数外参，再用桌面平面 RANSAC 细化；不需要在线估计 6D 相机位姿。**
- **pivot 近恒定**：`action.pivot` 的逐维名称是 `[vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]`。抽查的多数任务是 `[0, 0, 0, 0, 0.15, 0, 0.74]`；ArrangeTestTubes 高度 0.689、Unlock 0.717、FruitSorting 0.737、OrganizeTools 的 `pivot_3=-0.033, pivot_4=0.162`、FoldTowel 的 `pivot_4=0, height=0.74`。**结论：按任务从 `meta/stats.json` 取常数 pivot，比输出全零安全；全零可能改变下蹲/高度。**
- **夹爪不是 0–1**：`action.left_gripper` 范围约 0.01–4.5，`right_gripper` 0–4.5，`observation.state.*_gripper` 约 0–4.8。挑战赛 API 只写“Target gripper command”，没有量纲；adapter 必须按数据集范围和 `example_env.py` 校验，不能假设 0–1。
- **头双目已校正**：基线 58.2526 mm，`fx≈282.37`，`rectified: true`；头双目可做 0.5–1.0 m 的粗深度。腕部单目可用于近距离模板/轮廓伺服。

### 1.5 WLA 54D → 挑战赛 21D：相对 EE 在当前 EE 系，不是 base 系

官方 `unifolm-wla` 仓库与 `docs/robot_action_state_processing_en.md`（2026-11-01 复核）给出：

- 6B，约 2,500 h 真机数据，64 任务；默认 `chunk_size=30`、`target_fps=30`、4 步去噪；冻结 VLM，只训 DiT action head + state projector，单张 24GB GPU 可微调；2026-09-29 已加 LoRA。
- 动作 54 维：左 EE `[0:6]` 相对 xyz+rotvec、左夹爪 `[6:7]`、左手 `[7:13]`、右 EE `[13:19]`、右夹爪 `[19:20]`、右手 `[20:26]`、腰 `[26:29]`、躯干 `[29:32]`、base 平移 `[32:34]`、base yaw `[34:35]`、base pose `[35:41]`、height `[41:42]`、左腿 `[42:48]`、右腿 `[48:54]`。
- 状态 60 维：左右 EE 各 9 维（xyz + rot6d）+ 夹爪 + 手 + 腰 + 躯干 + base + 腿。
- **相对 EE 动作的平移在当前 EE 系**，旋转也是相对当前 EE 的 rotvec；训练时由 `T_rel = T_curr^{-1} T_future` 得到。adapter 必须先 `T_future = T_curr T_rel` compose 成 base 系绝对位姿，再转 xyz+rpy；不能把相对量直接当绝对量。
- 官方 Unitree 配置的字段与挑战赛数据完全对得上：`action.left_ee_pose_gripper_base`、`right_ee_pose_gripper_base`、`action.left_gripper`、`action.right_gripper`、`action.waist_action_joint`、`action.base_command`、`action.left_leg`、`action.right_leg`；图像角色是 `head_left` + 左右腕，**不用 head_right 进 VLA**，head_right 只用于双目深度。
- WLA 的 `pivot` 与挑战赛的 `action.pivot` 不是同一个字段：官方配置用 `base_command`（4D）+ `waist_action_joint`（3D），挑战赛用打包的 7D pivot。adapter 必须先按任务输出常数 pivot，再逐步验证是否要把 WLA 的 waist/base 写进去。

**战略结论**：不要再从零训 6B/14B。用官方 WLA Base 做 action-head/LoRA 微调，把省下的算力投到场景账本、绑定审计和单任务评测。挑战赛 API 的 `ee` 动作是 **2×6 绝对 EE + 2×1 夹爪 + 7 pivot = 21 维**；WLA 的 54D 需要一层薄 adapter。

### 1.6 近期工作：binding 是 VLA 的下一层瓶颈

**本轮的差异化**：把“反事实解释”从训练期/离线分析，变成**推理期的绑定证书 + 重绑触发器**；把“scene graph”从静态文本，变成**任务条件化、带角色和置信度的账本**；把“visual prompt”从通用 bbox，变成**角色感知的目标/受器指认**；把“多轮对话”从人类交互，变成**与场景的内部子目标协议**。这个组合在单模型、无人类通道、180s 真机约束下是新的。

## 2. 诊断：三种绑定失败

### 2.1 指代绑定：红色积木、红色盘子、红色碗

ColorArrangement 要红/绿/黄三块积木，FruitSorting 要水果→同色盘子，StackBowls 要红/绿/蓝三个碗。同一个“红色”在不同任务里指不同物体类别；同一场景里还有红色干扰物。VLA 的单次前向很容易被显著物体/熟悉布局吸走，尤其是“红色”在训练数据里总是和某个位置共现时。**这不是语义理解错，而是指代没有落到具体 instance 上。**

### 2.2 关系/顺序绑定：右到左、红绿黄、第一个插座、拼 “robot”

- ColorArrangement：右→左，红→绿→黄。
- ArrangePlates：右→左，红→绿→蓝。
- OrganizeTools：右→左。
- SpellRobot：字母顺序拼 “robot”。
- PlugCharger：第一个插座。
- OrganizeBookshelf：最上面的书。
- ConveyorSorting：传送带上的移动食物→右侧架子，按类别。
这些关系在图像里不是显式 token；VLA 必须自己从像素和语言里推断，而且要在动作序列中保持顺序。**单次前向没有“当前是第几个/下一个是谁”的显式状态，容易重复抓同一个或打乱顺序。**

### 2.3 状态绑定：动完没有、被人拿走了没有、子目标完成没有

- 多阶段任务（PackBag、OrganizePencilCase、StoreEarphones、ToolboxStorage）需要知道“上一步完成了没有”。
- 人为干扰轴会移动目标/受器/遮挡物；VLA 可能继续按旧计划走。
- chunk 内没有新观测；如果人在 chunk 中间移动物体，模型要等 1 秒后才知道。
**没有显式场景状态，模型只能把“完成/未完成”隐式编码在动作历史里；一旦被干扰，历史就错了。**

- **上层慢**：Scene Ledger + Internal Dialogue 在子目标边界运行，1–3 次 VLM/ episode。
- **中层中速**：VLA 30 步 plan，异步请求，不阻塞 `get_action`。
- **下层快**：CHUNK-SERVO 每 5 步用视觉/账本修正，负责最后 3 厘米。
- **审计旁路**：Binding Audit 可以在安全点同步，也可以在后台异步；结果用于下一个子目标的重绑。

### 3.2 Scene Ledger：任务条件化的场景账本

不是通用 scene graph，而是“为了当前指令和当前子目标，必须知道的最小场景状态”。

```python
@dataclass
class SceneObject:
    id: str                  # "block_red", "plate_green", "slot_1"
    cls: str                 # "block", "plate", "bowl", "cup", "tool", ...
    color: str               # "red", "green", "yellow", "blue", "none"
    pose_base: np.ndarray    # (x, y, z, yaw) 粗到 1–2cm
    bbox_head: tuple         # (u1, v1, u2, v2)
    bbox_wrist: tuple | None
    support: str | None      # 支撑面/容器 id
    container: str | None    # 所在容器 id
    visible: bool
    confidence: float        # 0–1
    last_seen: int           # frame index
    role: str                # "target" | "receptacle" | "distractor" | "unknown"

@dataclass
class SceneLedger:
    task_id: str
    scene_version: int       # 人为干扰/物体移动时 +1
    objects: dict[str, SceneObject]
    relations: dict[str, list[str]]  # left_of/right_of/on/in/stacked_on/same_color
    order: list[str]         # 当前任务要求的顺序
    completed: set[str]      # 已完成子目标/物体
    next_index: int          # 当前顺序索引
```

构建管线（全部确定性/经典算法，不训练第二个模型）：

1. **深度**：头双目 `cam_left_high`/`cam_right_high` → SGBM/BM（240×320 或 336×448）→ WLS 滤波 → 用头内参/基线反投影。
2. **桌面平面**：RANSAC 拟合平面，去掉桌面，得到物体点云候选；DBSCAN 聚类。
3. **物体候选**：HSV 颜色分割 + ORB 模板匹配（演示关键帧）+ 深度连通域；未见物品用同一 WLA 的 VLM 标注一次（不加载第二个检测器）。
4. **跟踪**：3D 位置 + 颜色 + bbox 的匈牙利匹配；遮挡时保留 last_seen，重新出现时按 appearance/geometry 重连；`scene_version` 在目标/受器被移动或新物体出现时 +1。
5. **关系**：左/右按桌面坐标系投影排序；上/下按 z；on/in 按垂直距离 + 包含；stacked_on 按 z-order；same_color 按 HSV；order 按任务指定的轴（如 right-to-left）排序。
6. **角色**：用任务 schema（§3.3）把指令里的 target/receptacle/order/count 映射到账本对象；未见物品/歧义时让 VLM 从候选列表里选，输出 id，不输出自由文本。
7. **置信度**：几何（有效深度像素比例、点云点数）、外观（模板分数）、语义（VLM 候选概率）、时序（track age）加权；低于 0.6 不用于视觉指认，只用于粗定位。

更新频率：5–10 Hz，不要每 30Hz 帧都跑 SGBM；子目标边界强制刷新一次。所有状态 per-port 隔离，`reset()` 清空。

### 3.3 Internal Multi-turn Protocol：与场景对话，不是与人对话

任务 schema 先把指令编译成可执行结构，而不是让 VLA 直接吃一整句：

```json
{
  "task_id": "T06",
  "action": "arrange",
  "objects": {"cls": "block", "count": 3},
  "order": ["red", "green", "yellow"],
  "axis": "right_to_left",
  "receptacle": null,
  "constraints": ["same_row", "right_to_left"]
}
```

更多例子：

| 指令 | schema |
|---|---|
| Put all the fruits into the fruit basket. | `{action:"collect_all", target:{cls:"fruit"}, receptacle:{cls:"basket"}}` |
| Place each fruit onto the plate with the matching color. | `{action:"sort", target:{cls:"fruit"}, receptacle:{cls:"plate"}, match:"color"}` |
| Put the top book onto the bookshelf. | `{action:"pick_place", target:{cls:"book", superlative:"top"}, receptacle:{cls:"bookshelf"}}` |
| Open the pencil case zipper, place all stationery items into the pencil case, and close the zipper. | `{action:"sequence", steps:["open_zip","collect_all","close_zip"], target:{cls:"stationery"}, receptacle:{cls:"pencil_case"}}` |
| Use the syringe to transfer water from the large cup to the small cup. | `{action:"tool_transfer", tool:{cls:"syringe"}, source:{cls:"cup", size:"large"}, target:{cls:"cup", size:"small"}}` |

schema 用 32 条官方指令的模板/正则即可覆盖大部分；未见/复杂指令回退给 WLA VLM 输出同一 schema。schema 是**可解释的中间表示**：失败时能看出是“目标错、受器错、顺序错、还是数量错”。

对话状态机：

```text
INIT
  └─ ASK_TASK      # 解析指令 → task schema
       └─ GROUND   # 账本返回候选/关系；planner 选 target/receptacle
            └─ PLAN        # 输出 subgoal JSON + expected_effect
                 └─ ACT    # VLA plan + visual marker + CHUNK-SERVO
                      └─ CHECK   # 账本验证 expected_effect + Binding Audit
                           ├─ pass ──▶ next subgoal / DONE
                           ├─ fail ──▶ REVISE（重绑/重规划）
                           └─ edit ──▶ RECOVER（停→重定位→重绑→重规划）
```

每轮的 typed message：

| Turn | 发送方 | 内容 | 是否调用 VLM |
|---|---|---|---|
| `ASK_TASK` | policy | 指令 + 32 任务 schema 模板 | 否（模板匹配）/ 是（回退） |
| `GROUND` | ledger | 候选物体 id、pose、关系、置信度 | 否 |
| `PLAN` | VLM | `{subgoal, target_id, receptacle_id, expected_effect}` | **是，1 次** |
| `CHECK` | ledger | `{completed: bool, evidence, scene_version}` | 否 |
| `REVISE` | VLM | `{new_target_id, new_receptacle_id, reason}` | **是，仅失败时** |
| `RECOVER` | ledger+VLM | 重新 GROUND；必要时 PLAN | 是，仅干扰时 |

预算：正常 episode 1 次 PLAN；有 1 次失败/干扰则 2–3 次；绝不超过 3 次。每次 VLM 调用只处理**当前子目标**，输入是缩小的头图 + 腕图 + 账本候选列表（不是整段对话历史），输出是短 JSON，控制在 128 token 内。

### 3.4 Visual Target Prompting：把“我说的那个”画给 VLA 看

账本确定 target/receptacle 后，在送入 VLA 的图像上画角色感知的标记：

| 角色 | 颜色 | 画法 |
|---|---|---|
| target | spring green | 2px 框 + 左上角小标签 `T` + 抓取点十字 |
| receptacle | cyan | 2px 框 + 标签 `R` + 中心十字 |
| next | orange | 虚线框 + 标签 `N`（仅顺序任务） |
| distractor | magenta | 1px 框 + 标签 `D`（仅审计可视化，可不进 VLA） |
| gripper→target | yellow | 一条细线/箭头，表示当前子目标关系 |

原则：

- **不遮挡物体内部**；只画边框/十字/小标签。透明区域保持原图。
- 头图负责全局绑定（哪个物体/哪个受器），腕图负责局部抓取/插入点；不要在两幅图上画重复的大框。
- 标记是**假设**，不是硬约束；置信度 <0.6 不画，避免把错的目标“喂”给 VLA。
- 先零样本 A/B：同一模型、同一任务，标记开/关各 10 次。若标记在接触任务上掉点，改成只画腕图/只画细框/降低透明度。
- 如果后续做 LoRA，训练时也要随机开/关标记，避免模型只会“读框”不会“读图”。

### 3.5 Binding Audit：模型到底在看谁

对当前子目标，做两类反事实：

**A. 视觉 ROI mask**

\[
S_o = \mathbb{E}_{\epsilon}\left\| a(I,l;\epsilon) - a(I\odot(1-M_o),l;\epsilon) \right\|_2
\]

- \(M_o\)：物体 \(o\) 的 mask/bbox（可膨胀 2–4px）。
- \(\epsilon\)：flow-matching 噪声；固定 seed 做配对比较，降低方差。
- 对照：在空白桌面画同样大小的 mask，得到 \(S_{bg}\)；mask 一个明确无关的干扰物，得到 \(S_{distractor}\)。

**B. 语言反事实**

\[
S_{lang} = \left\| a(I,l) - a(I,l') \right\|_2
\]

- \(l'\)：把指令里的目标词替换成另一个候选（如 red→green），其余不变。
- 如果 \(S_{lang}\) 接近 0，说明策略几乎不看语言，只靠视觉 shortcut；这正是 CAG/CofactVLA 描述的现象。

**Binding margin**：

\[
M_s = S_{role(s)} - \max_{o \notin \{target, receptacle\}} S_o
\]

- \(role(s)\) 是当前子目标的主角色（pick 阶段是 target，place 阶段是 receptacle）。
- \(M_s > \tau\)：绑定可信；继续。
- \(M_s \le \tau\)：触发重绑：先加/换视觉标记，再重跑 PLAN；仍不行就用 CHUNK-SERVO 直接朝账本目标走；目标不可见则 RECOVER。
- 建议初始 \(\tau=0.02\)（归一化动作尺度），用单任务通道校准。

**Binding Certificate**（每个子目标一条，写入日志）：

```json
{
  "task_id": "T06",
  "subgoal": 1,
  "target_id": "block_red",
  "receptacle_id": "slot_1",
  "scene_version": 0,
  "ledger_confidence": 0.91,
  "S_target": 0.184,
  "S_receptacle": 0.121,
  "S_distractor_max": 0.043,
  "S_bg": 0.019,
  "margin": 0.078,
  "S_lang": 0.096,
  "decision": "accept",
  "action_chunk_norm": 0.73
}
```

这张证书就是“可解释性”的产物：它不是说“注意力在这里”，而是说“如果把目标遮住，动作会变 0.184；如果遮住最大的干扰物，只变 0.043；所以模型确实在看目标”。它还能在失败后被回放，区分“账本错”“VLA 没看”“语言没生效”“控制没到位”。

**成本**：一次 mask 前向 ≈ 一次 VLA chunk 前向。4 个 mask × 2–4 个子目标 = 8–16 次前向/episode，约 2–6s（取决于 GPU）。**不能同步塞进 `get_action`**；放在子目标边界的安全点，或后台 worker 异步跑，用上一子目标的结果指导下一子目标。在线只跑语言反事实（1 次前向）作为低成本版本；完整视觉审计用于离线任务筛选和单任务通道。

### 3.6 Subgoal Verification + Human-edit Rebinding

**子目标验证**：每个 subgoal 带 `expected_effect`，例如：

- `block_red` 不再在桌面，且出现在 `slot_1` 的容器内；
- `gripper` 闭合且 `block_red` 随夹爪刚性运动（`r_grasp` 小）；
- `pencil_case` 的拉链头位移超过阈值；
- `bowl_red` 在 `bowl_green` 上方，z-order 正确。

账本用几何/可见性检查，不调用 VLM：

```python
def check(subgoal, ledger):
    if subgoal.effect == "object_at":
        return (ledger.objects[subgoal.target_id].container == subgoal.receptacle_id
                and ledger.objects[subgoal.target_id].visible)
    if subgoal.effect == "grasped":
        return ledger.grasp_residual(subgoal.target_id) < 0.01
    if subgoal.effect == "zipped":
        return ledger.zipper_displacement(subgoal.receptacle_id) > 0.02
    ...
```

**人为干扰重绑**：

- 触发：`scene_version` 变化、目标/受器 pose 跳变 >2cm、目标消失/新物体出现、VLA 动作与账本目标方向相反。
- 动作：`STOP`（返回安全 hold/上一个合法 chunk）→ `RE-GROUND`（重新检测/跟踪）→ `REVISE`（更新 target/receptacle id）→ `PLAN`（新子目标）。
- 不重启 episode；不要求人重新给指令；不把旧计划的剩余 chunk 继续执行。
- 目标：human 轴 2/10 trials；如果这 2 次能从 0 恢复到 1，单任务 +20pp，全局 +2pp。

### 3.7 与 CHUNK-SERVO 的分工

| 层 | 频率 | 输入 | 输出 | 失败时 |
|---|---|---|---|---|
| SCENE-TURN / planner | 子目标边界，1–3 次/episode | 指令 + 头/腕图 + 账本候选 | subgoal JSON + target/receptacle id | 重绑/回退 VLA |
| VLA action head | 每 30 步（约 1s） | 标记后的头/腕图 + 状态 + subgoal | 30 步相对 EE 计划 | 用旧 plan + 伺服 |
| CHUNK-SERVO | 每 5 步（约 167ms） | 腕/头图 + 账本目标 + VLA 前馈 | 5 步修正后的绝对 EE | 回退 VLA 前馈 |
| Binding Audit | 子目标边界/后台 | 当前图 + mask/语言反事实 | margin + certificate | 触发重绑 |

关键：**SCENE-TURN 不替代 CHUNK-SERVO，CHUNK-SERVO 也不替代 SCENE-TURN**。账本给伺服一个“动哪个/到哪”的目标；伺服给账本一个“最后 3 厘米有没有到位”的反馈。两者共享同一个 WLA checkpoint，不新增学习模型。

### 3.8 可选 DEMO-DIALOGUE LoRA：把 33k 演示变成内部对话语料

如果零样本 SCENE-TURN 的绑定准确率不够，再做一个小 LoRA，而不是从头训：

1. **离线转录**：对每条演示，用账本 + 任务 schema + 夹爪事件，切成 2–6 个子目标；每个子目标生成一条 `(instruction, ledger_summary) → subgoal_json`。
2. **反事实增强**：把目标颜色/位置/顺序/干扰物随机替换，生成“如果 red 换成 green，目标应该是谁”的负例；这教 binding，不是教像素记忆。
3. **训练**：只对 WLA 的 VLM 做 LoRA（官方已支持），action head 冻结或小 LoRA；输入是缩小的头/腕图 + 账本 JSON + 指令，输出是 subgoal JSON；不训练新的检测器。
4. **门控**：离线 subgoal 准确率 +10pp 才上真机；真机只在 binding-heavy 任务上 A/B；接触任务不启用，避免破坏 primitive。

风险：LoRA 可能过拟合账本格式；用 20% 任务做 held-out，用反事实增强，用零样本先跑基线。

## 4. 为什么现在能做

- **官方 WLA Base 已开源**：6B、24GB 可微调、LoRA 已支持；不用从零训。
- **33k 演示 + 5 条同义指令/任务**：既能做 behavior cloning，也能做内部对话语料；语言不是单一的。
- **腕部内参已提供、头外参近恒定、pivot 近恒定**：确定性几何终于可行；不需要在线估 6D 相机位姿。
- **32 条官方指令已拿到**：可以手写任务 schema/正则，不必靠 VLM 猜任务。
- **公开研究已证明 binding 是真瓶颈**：Robust Skills/Brittle Grounding、EmbodimentSemantic、CAG、CofactVLA、ActGaze 都指向“语言→物体/区域绑定”是失败源；但还没有人把它做成**单模型、推理期、带证书、可重绑**的竞赛方案。
- **竞赛的 5 条泛化轴就是 5 条 binding 轴**：位置/干扰物/背景/未见物品/人为干扰；其中 human 轴占 20%，SCENE-TURN 的重绑直接打这个轴。

## 5. 竞赛策略：把 320 trials 投到 binding 轴

### 5.1 任务组合（先验，待单任务通道更新）

| 组 | 任务 | 主武器 | 预期 |
|---|---|---|---|
| **Binding-heavy** | ColorArrangement、ArrangePlates、StackBowls、SpellRobot、FruitSorting、OrganizeStationery、OrganizePencilCase、ToolboxStorage、PackBag、ConveyorSorting | SCENE-TURN + 视觉指认 + 顺序验证 | 目标 +5–10pp |
| **Contact-heavy** | HangCup、DisconnectEthernet、PlugCharger、Unlock、ZipUp、PlugInEthernet、RemovePinnedNote、SyringeWaterTransfer | CHUNK-SERVO + DG-KEYFRAME | 目标 +3–8pp |
| **Both** | PackDoll、StoreEarphones、ArrangeTestTubes、PaperCupStacking、StoreCups、StorePaddle、PackPhone、PlacePhotoFrame | SCENE-TURN 选目标/顺序 + CHUNK-SERVO 收尾 | 目标 +5pp |
| **VLA baseline** | FoldTowel、PourOutMedicine、其余变形/长程 | 官方 WLA + 正确 adapter | 不掉点 |

### 5.2 320 trials 的算术

- 32 任务 ×10 = 320 trials；human 轴每任务 2 次，共 64 次（20%）。
- 若 SCENE-TURN 让 10 个 binding-heavy 任务各 +8pp：全局 `10×8/32 = +2.5pp`。
- 若 human 轴 +10pp：全局 `0.2×10 = +2.0pp`。
- 若子目标验证让步骤分 +3：在成功率相同的 tie-break 里直接有利。
- 成本：1–3 次 VLM/episode + 5–10Hz 账本；不抢 CHUNK-SERVO 的 GPU 预算；延迟通过异步 planner 控制。

### 5.3 提交节奏

1. **Baseline**：官方 WLA + 正确 adapter（绝对 EE、pivot 常数、gripper 量纲）；先锁一个能跑完 320 trials 的安全基线。
2. **SCENE-TURN zero-shot**：只开账本 + 视觉标记 + 子目标验证，不做 LoRA；在 5 个 binding-heavy 任务上单任务 A/B。
3. **Binding Audit**：离线跑证书，验证 margin 与成功/失败的相关性；在线只开语言反事实。
4. **CHUNK-SERVO 合流**：在 contact-heavy 任务上开 5 步伺服；用账本目标做 PBVS。
5. **LoRA（可选）**：只有前 4 步证明 binding 是瓶颈且零样本不够时才做。

| **G5** | 人为干扰能不能重绑 | 模拟人移动目标/受器 20 次：恢复成功率 >50%，恢复时间 <3s | 加 scene_version/重定位；退回 VLA |

| **G7** | 竞赛合规 | 单模型/单 checkpoint；N 端口隔离；token 正确；320 trials 无崩溃；动作无异常 | 回退 baseline |
| **G8** | LoRA 值不值 | 离线 subgoal +10pp；真机 binding-heavy +3pp；contact 不掉 | 不做 LoRA，保留零样本 |

## 7. 风险与合规

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 账本检测错，标记错目标 | 中 | 高 | 置信度门控；审计；回退 VLA；只用粗定位 |
| 视觉标记反而干扰 VLA | 中 | 中 | 零样本 A/B；腕图/细框/低透明度；可关闭 |
| VLM planner 延迟抖动 | 中 | 高 | 异步；1–3 次/episode；缓存；缩小图；不阻塞 `get_action` |
| 审计太贵 | 高 | 中 | 离线/异步；在线只语言反事实；证书只记不实时跑 |
| 被判定“第二个模型” | 低 | 高 | 只用官方 WLA checkpoint；账本是确定性 CV；无第二个学习检测器；文档写清 |
| 人为干扰不可预测 | 高 | 中 | `scene_version` + 重定位 + 重绑；不重启 episode |
| 顺序任务的状态机卡死 | 中 | 中 | 超时/重试上限；失败回退 VLA；步骤分保底 |
| 夹爪/pivot 量纲错 | 中 | 高 | G0 先验；用 `example_env.py` 和数据集 stats 校准 |

**单模型合规**：

- 只有一份 WLA 权重；planner 是同一 checkpoint 的 VLM（可 LoRA，属于同一模型）。
- 账本用 SGBM/RANSAC/HSV/ORB/匈牙利匹配，全是经典算法，无训练权重；不是“第二个模型”。
- 伺服是确定性控制器；不是学习残差策略。
- 每端口独立 `reset()`；账本/对话/plan 状态不跨端口共享；共享的只有模型权重。
- 不做跨 episode 在线学习、不做测试时训练、不下载隐藏测试数据。

# 第 13 轮产物 · SCENE-TURN 技术报告

> 检索/复核日期：**2026-11-01（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「SCENE-TURN」的工程化产物；它**不替换**第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是在它们之上补一层 binding：**SCENE-TURN 决定“动哪个/动到哪/按什么顺序/动完没有”，CHUNK-SERVO 决定“最后 3 厘米怎么动”，VLA 决定“动作长什么样”。**

## 0. 结论与边界

### 0.1 一句话结论

官方 WLA 的 30 步 action chunk 解决了“动作像不像人”，CHUNK-SERVO 解决了“最后 3 厘米准不准”，但 32 条官方指令里有 20+ 条要求把**指代、颜色、顺序、空间关系、嵌套关系**绑定到当前场景；这层 binding 目前既没有显式状态，也没有运行时验证。SCENE-TURN 用**任务条件化 Scene Ledger + 1–3 轮内部 ASK/GROUND/CHECK/REVISE + 角色感知视觉指认 + 反事实 Binding Audit**，在不新增学习模型的前提下，把 binding 变成可检查、可重绑、可解释的控制量。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、排行榜 JSON、官方仓库代码直接核实 | 规则、API、33,276 eps、WLA 54D 布局、pivot 名称、腕部内参 |
| B | 我们在公开数据/网页上做的分析，可复现 | 榜单 `step~success` 回归、跨模型任务相关、`state_d435` 方差、pivot 抽样 |
| C | 设计假设，需 G0–G8 验证 | 视觉标记 +5pp、audit margin AUC>0.7、human 轴恢复 >50% |

### 0.3 本轮不做什么

- 不从零训 VLA/World Model；官方 WLA Base 已开源。
- 不做第二个学习检测器/6D pose 网络；账本用经典 CV + 同一 WLA 的 VLM 标注。
- 不做人类语音/聊天对话；API 没有通道。
- 不做每步 VLM 调用；planner 只在子目标边界异步调用。
- 不做通用 scene-graph 大模型；只做任务条件化的最小账本。
- 不做测试时训练/跨 episode 在线学习。
- 不把预览榜单的任务排名当难度表。
- 不假设夹爪是 0–1、pivot 是零、腕部无内参；这些都要按数据校准。

## 1. 事实核对

### 1.1 比赛规则（A）

官方参赛手册（飞书中文/英文 docx，2026-11-01 复核；通过 `r.jina.ai` 抓取，部分章节可能截断，最终以官方页面为准）：

| 项 | 规则 |
|---|---|
| 模型 | 所有任务须基于**同一模型**完成，不得混合多个模型一起测试；模型类型不限 |
| 任务 | 32 项桌面任务 |
| 次数 | 每任务 10 次独立运行 |
| 泛化 | 5 类各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰 |
| 时限 | 单次真机执行上限 **180 s** |
| 排名 | 先比 32 任务总平均成功率；相同看总平均步骤分；再相同看更早提交 |

**对方案的约束**：SCENE-TURN 必须每端口独立、CPU 轻量、不抢 GPU；planner 必须是同一 WLA checkpoint 的 VLM；账本/伺服是确定性组件；所有 A/B 先在单任务通道做。

### 1.2 提交 API（A）

提交模板 README（2026-11-01 复核）给出：

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640** |
| 本体 | 双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str` |
| 动作空间 | `control_space` 仅 `"joint"` 或 `"ee"`，二者互斥 |
| 共享动作 | `action.left_gripper [1]`、`action.right_gripper [1]`、`action.pivot [7]` |
| EE 动作 | `action.left_ee_pose_gripper_base [6]`、`action.right_ee_pose_gripper_base [6]`（**绝对目标位姿**，xyz+rpy，base 系） |
| chunk | `action_chunk_size` ≥1，固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action` |
| token | `metadata.token` 握手校验一次；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile** |
| 监控 | 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分 |

**关键推论**：

- `action_chunk_size=30`、控制频率 30Hz 时，一次 `get_action` 之后有 **1 秒开环执行**；chunk 内没有新观测，也没有打断机制。
- `observation.language` 是**单个 `str`，episode 内不变，没有时间轴**；没有人类对话通道。
- `action.pivot` 只写“Lower-body / pivot target”，没有逐维语义；不能猜。
- `get_action` 的延迟会被记录；planner 不能同步阻塞，否则延迟抖动会被看见。

## 2. 问题形式化

### 2.1 Binding 问题

给定指令 \(l\)、图像 \(I_t\)、本体状态 \(s_t\)，VLA 输出动作 chunk \(a_t\)。标准 VLA 只建模：

\[
a_t \sim \pi(\cdot \mid I_t, s_t, l)
\]

SCENE-TURN 显式引入场景状态 \(Z_t\) 和子目标 \(g_t\)：

\[
Z_t = \mathrm{Ledger}(I_t, s_t, l),\qquad
g_t = \mathrm{Planner}(l, Z_t),\qquad
a_t \sim \pi(\cdot \mid \mathrm{Mark}(I_t, g_t, Z_t), s_t, l, g_t)
\]

binding 错误可以拆成：

\[
P(\text{fail}) \approx P(\text{wrong target}) + P(\text{wrong receptacle}) + P(\text{wrong order}) + P(\text{stale state}) + P(\text{control}).
\]

SCENE-TURN 直接攻击前四项；CHUNK-SERVO 攻击最后一项。

### 2.2 任务 schema

把指令编译成 typed JSON，而不是让 VLA 直接吃整句：

```json
{
  "task_id": "T06",
  "action": "arrange",
  "objects": {"cls": "block", "count": 3},
  "order": ["red", "green", "yellow"],
  "axis": "right_to_left",
  "receptacle": null,
  "constraints": ["same_row", "right_to_left"]
}
```

支持的 action 类型（覆盖 32 任务）：

| action | 例子 | 关键字段 |
|---|---|---|
| `collect_all` | FruitCollection、OrganizeStationery | `target.cls`, `receptacle.cls` |
| `sort` | FruitSorting、StackBowls | `target.cls`, `receptacle.cls`, `match` |
| `arrange` | ColorArrangement、OrganizeTools | `order`, `axis` |
| `pick_place` | HangCup、OrganizeBookshelf | `target`, `receptacle`, `superlative` |
| `sequence` | PackBag、OrganizePencilCase | `steps[]` |
| `tool_transfer` | SyringeWaterTransfer、Unlock | `tool`, `source`, `target` |
| `deform` | FoldTowel | `target`, `fold_spec` |
| `dynamic_sort` | ConveyorSorting | `source=conveyor`, `match=category` |

用 32 条官方指令的模板/正则 + 少量同义词即可覆盖大部分；未见/复杂指令回退给 WLA VLM 输出同一 schema。schema 是**可解释中间表示**：失败时能区分目标错、受器错、顺序错、数量错。

### 2.3 Scene Ledger 状态

```python
@dataclass
class SceneObject:
    id: str
    cls: str
    color: str
    pose_base: np.ndarray      # (x, y, z, yaw)
    bbox_head: tuple
    bbox_wrist: tuple | None
    support: str | None
    container: str | None
    visible: bool
    confidence: float
    last_seen: int
    role: str                  # target/receptacle/distractor/unknown

@dataclass
class SceneLedger:
    task_id: str
    scene_version: int
    objects: dict[str, SceneObject]
    relations: dict[str, list[str]]
    order: list[str]
    completed: set[str]
    next_index: int
```

约束：

- **任务条件化**：只维护当前指令/子目标相关的物体和关系；不是全场景 3D 重建。
- **粗到 1–2cm**：账本负责“哪个/在哪/什么关系”；最后 3mm 交给 CHUNK-SERVO。
- **可失效**：`confidence < 0.6` 的物体不用于视觉指认；`scene_version` 变化时重绑。
- **per-port 隔离**：每个端口独立 `SceneLedger`；`reset()` 清空。

### 2.4 Binding Audit 指标

视觉反事实：

\[
S_o = \mathbb{E}_{\epsilon}\left\| a(I,l;\epsilon) - a(I\odot(1-M_o),l;\epsilon) \right\|_2
\]

语言反事实：

\[
S_{lang} = \left\| a(I,l) - a(I,l') \right\|_2
\]

binding margin：

\[
M_s = S_{role(s)} - \max_{o \notin \{target, receptacle\}} S_o
\]

判定：

- \(M_s > \tau\)：绑定可信，继续。
- \(M_s \le \tau\)：重绑/重规划/回退。
- \(S_{lang} < \tau_{lang}\)：策略基本不看语言，优先修语言条件（视觉指认/子目标 prompt）。

### 2.5 延迟预算

| 组件 | 频率 | 预算 | 备注 |
|---|---|---:|---|
| SGBM 深度（240×320） | 5–10 Hz | 5–15 ms | CPU，可降分辨率 |
| Ledger 更新 | 5–10 Hz | 10–30 ms | 只在有足够新帧时 |
| 视觉标记 | 每 chunk | <5 ms | OpenCV 画框 |
| VLM planner | 1–3 次/episode | 0.5–1.5 s/次 | **异步**，不阻塞 `get_action` |
| VLA 30 步 chunk | 每 1 s | 0.2–0.5 s | GPU，共享 server |
| Binding Audit（4 masks） | 子目标边界/后台 | 0.8–2.0 s | 离线/异步；在线只语言反事实 |
| `get_action` p95 | 每 chunk | 目标 <50 ms（不含异步 planner） | evaluator 会记录 |

**原则**：`get_action` 永远返回合法 chunk；planner/audit 慢时用旧 plan + 伺服；绝不返回 NaN/超时。

### 3.1 进程/端口拓扑


### 3.3 动作 adapter：WLA 54D → 挑战赛 21D

**输入**：WLA 的 30×54 动作 chunk、当前左右 EE 绝对位姿 \(T_{L}, T_{R}\)、每任务 pivot 常数 \(p\)、夹爪量纲。

**输出**：挑战赛 `ee` 模式的 5×21：

```text
left_ee_abs[6], right_ee_abs[6],
left_gripper[1], right_gripper[1], pivot[7]
```

**公式**：

```python
def wla54_to_api21(rel54, T_left_cur, T_right_cur, pivot_const):
    # rel54: (30, 54), translation in current EE frame, rotation rotvec
    T_left_rel  = se3_from_xyz_rotvec(rel54[:, 0:6])
    T_right_rel = se3_from_xyz_rotvec(rel54[:, 13:19])

    T_left_abs  = T_left_cur  @ T_left_rel    # (30, 4, 4)
    T_right_abs = T_right_cur @ T_right_rel

    left_xyz_rpy  = se3_to_xyz_rpy(T_left_abs)
    right_xyz_rpy = se3_to_xyz_rpy(T_right_abs)

    left_gripper  = denorm_gripper(rel54[:, 6:7],  side="left")   # 0–4.5, not 0–1
    right_gripper = denorm_gripper(rel54[:, 19:20], side="right")

    pivot = np.tile(pivot_const, (len(rel54), 1))  # per-task constant, e.g. [0,0,0,0,0.15,0,0.74]
    return left_xyz_rpy, right_xyz_rpy, left_gripper, right_gripper, pivot
```

**关键细节**：

1. **帧**：`T_rel = T_curr^{-1} T_future`，所以 `T_future = T_curr T_rel`。平移在当前 EE 系；旋转也是相对当前 EE。
2. **切片**：先把整个 30 步 compose 成绝对目标，再按 5 步切片；不要先切相对量再 compose，否则第 6–30 步的锚点会错。
3. **TCP**：WLA 的 EE 帧可能与挑战赛 `*_ee_pose_gripper_base` 差一个夹爪长度/工具偏移；G0 用数据集和 `example_env.py` 校准（平移 ≤1cm、旋转 ≤2°）。
4. **pivot**：按任务从 `meta/stats.json` 取常数；不要输出全零。`pivot_3..5` 语义未核实，先复制，不要猜。
5. **夹爪**：0–4.5 量纲；用数据集 `action.*_gripper` 的 q01/q99 做 minmax；不要假设 0–1。
6. **失败安全**：任何 NaN/形状错/超时 → 返回上一组合法 chunk 或安全 hold；绝不返回异常动作。

### 3.4 `get_action` 伪代码

```python
class SceneTurnPolicy:
    def __init__(self):
        self.ledger = SceneLedger()
        self.schema = None
        self.plan = None
        self.plan_idx = 0
        self.subgoal = None
        self.future = None
        self.audit_future = None
        self.last_safe = None

    def get_action(self, obs):
        self._ingest(obs)                 # update ledger, scene_version
        self._maybe_parse_task(obs)       # one-time task schema
        self._maybe_request_plan(obs)     # async VLM, never block

        if self.plan is None:
            self.plan = self._safe_hold(obs)   # cold start / planner late

        if self.subgoal and self.subgoal.mode == "SERVO":
            a_ff = self.plan[self.plan_idx:self.plan_idx + self.H]
            delta = self.servo.compute(obs, self.subgoal, self.ledger)
            a_cmd = compose_relative(a_ff, delta)
        else:
            a_cmd = self.plan[self.plan_idx:self.plan_idx + self.H]

        self.plan_idx += self.H
        if self.plan_idx >= len(self.plan):
            self.plan_idx = 0
            self.plan = None

        out = self.adapter.to_api(a_cmd, obs, self.token)
        self.last_safe = out
        return out

    def _maybe_request_plan(self, obs):
        if self.future is not None and not self.future.done():
            return
        if self.future is not None:
            self.subgoal = self.future.result()
            self.future = None
            self._maybe_audit(obs, self.subgoal)
        if self.plan is None or self._subgoal_boundary():
            snapshot = copy_obs(obs)
            self.future = self.executor.submit(self._plan, snapshot)
```

规则：

- VLA/planner 永远不阻塞 `get_action`（除冷启动）；plan 过期就用旧 plan + 伺服。
- 每个 chunk 只做一次伺服；伺服失败不影响返回合法动作。
- 任何异常 → 返回上一组合法 chunk 或安全 hold。
- 审计在后台 worker 跑；结果只影响下一个子目标，不在当前 chunk 里等。

## 4. Scene Ledger 算法

### 4.1 深度

- 头双目 `cam_left_high`/`cam_right_high`；先确认是否已校正（数据集 `rectified: true`；API 图像应与数据一致）。
- SGBM/BM 参数：`numDisparities=64/128`、`blockSize=5/7`、`uniquenessRatio=10`、`speckleWindowSize=50`；WLS 滤波可选。
- 反投影：用头左内参 \(K_L\)、基线 \(b=0.0582526\) m；\(Z = f_x b / d\)，\(X=(u-c_x)Z/f_x\)，\(Y=(v-c_y)Z/f_y\)。
- 0.5–1.0m 工作距离，视差约 16–33px；深度误差约 \(Z^2/(f b)\)，1m 处约 6cm/px 视差；账本只用粗深度，精密对齐交给伺服。
- 透明/反光物体：深度缺失 → 用颜色/模板/腕部单目 + 先验尺寸；置信度低不建精确目标。

### 4.2 桌面平面与物体候选

1. RANSAC 拟合平面 \(ax+by+cz+d=0\)，取最大平面为桌面。
2. 去掉桌面内点；剩余点云 DBSCAN（eps≈1.5cm，min_samples≈20）。
3. 每个 cluster → 3D bbox、质心、主轴；投影回头图/腕图得到 bbox。
4. 与上一帧 track 做匈牙利匹配：代价 = 3D 距离 + 颜色距离 + bbox IoU；阈值 3cm/0.3 IoU。
5. 新 cluster 若面积/高度像物体，分配新 id；`scene_version += 1`。

### 4.3 颜色/模板/VLM 标注

- **颜色**：HSV 阈值（red 两段 hue、green、yellow、blue）；输出颜色 + 像素占比；对红色积木/盘子/碗用同一颜色标签，靠 `cls` 区分。
- **模板**：从演示关键帧取 ORB 模板（工具、瓶子、耳机盒、锁）；只在腕图近距离匹配；inlier ≥15 才信。
- **VLM 标注**：未见物品/类别不确定时，调用同一 WLA VLM，输入候选 bbox + 任务指令，输出 `cls` 和候选 id；**不输出自由文本坐标**；每 episode 最多 1–2 次。
- **融合**：颜色/模板/VLM 三路投票；置信度 = 加权几何×外观×语义×时序；低于 0.6 只做粗定位。

### 4.4 跟踪、关系、顺序

- **id 持久化**：物体被夹住/遮挡时保留 id；`visible=False`；重新出现按 3D 位置 + 颜色 + 模板重连；不要每帧新建 id。
- **关系**：
  - `left_of/right_of`：按桌面坐标系的 \(x\) 投影排序；任务说 right-to-left 就降序。
  - `on/in`：垂直距离 <2cm 且水平投影在支撑面内 → on；容器 bbox 内含 → in。
  - `stacked_on`：z-order + 水平重叠 >50%。
  - `same_color`：HSV 类别相同。
  - `top`：同一支撑面上 z 最高/可见性最好的物体。
- **顺序**：从 schema 的 `order` 生成 `order_ids`；`next_index` 指向下一个未完成目标；完成一个就 `completed.add(id)`；不要靠 VLA 自己记顺序。
- **数量**：schema 的 `count` 与账本中匹配物体数比较；少于 count → 搜索/重扫；多于 count → 选置信度最高/最靠前的。

### 4.5 置信度与失败模式

| 失败 | 检测 | 处理 |
|---|---|---|
| 深度缺失/透明 | 有效视差 <30% | 用颜色/模板/腕部；置信度降级 |
| 物体遮挡 | track 丢失 | 保留 last_seen；用另一视角；等 1–2 帧 |
| 颜色混淆 | 多物体同色 | 用 `cls`/位置/顺序区分；置信度低不指认 |
| 人为移动 | pose 跳变 >2cm / scene_version | 重定位/重绑；不继续旧 plan |
| 新物体 | 新 cluster | 分配 id；若指令涉及未见物品，VLM 标注 |
| 容器内不可见 | 目标消失但 expected_effect 未达成 | 用夹爪/腕图验证；必要时 VLA 重规划 |

## 5. 视觉指认（Visual Target Prompting）

### 5.1 画什么

| 角色 | 颜色 | 头图 | 腕图 |
|---|---|---|---|
| target | spring green | 2px bbox + `T` 标签 + 抓取点十字 | 2px bbox + 抓取点十字 |
| receptacle | cyan | 2px bbox + `R` 标签 + 中心十字 | 若可见则小框 |
| next | orange | 虚线 bbox + `N` | 不画 |
| distractor | magenta | 1px bbox + `D`（审计可视化） | 不画 |
| gripper→target | yellow | 细箭头 | 可选 |

原则：

- 不遮挡物体内部；只画边框/十字/小标签；透明区域保持原图。
- 头图负责全局绑定；腕图负责局部抓取/插入；不要重复大框。
- 置信度 <0.6 不画；错标比不标更糟。
- 先零样本 A/B；若掉点，改成腕图细框/低透明度/只画 target。
- 若做 LoRA，训练时随机开/关标记，避免只会读框。

### 5.2 与 VLA 输入的关系

- VLA 输入是 `head_left` + 左右腕；标记画在送入 VLA 的图像上。
- 头右只用于深度；不要画标记（WLA 不看）。
- 标记坐标来自账本 bbox；如果账本用 480×640、VLA 用 336×448，按比例缩放后再画。
- 标记不改变语言；语言保持官方指令原文，避免分布外 prompt。

## 6. Binding Audit

### 6.1 视觉反事实

```python
def visual_audit(vla, obs, target_id, receptacle_id, distractor_ids, seed=0):
    base = vla.predict(obs, seed=seed)
    results = {}
    for oid in [target_id, receptacle_id, *distractor_ids, "__bg__"]:
        mask = make_mask(obs, oid)  # bbox/segmentation; bg = random empty patch
        cf = vla.predict(apply_mask(obs, mask), seed=seed)
        results[oid] = np.linalg.norm(base - cf)
    return results
```

- mask 用 bbox 膨胀 2–4px 或分割 mask；背景对照用同尺寸空白桌面 patch。
- 固定 seed 做配对；flow matching 的噪声相同，减少方差。
- 动作差用前 5 步的 L2，按动作尺度归一化（除以数据集动作 q99-q01）。
- 目标/受器/最大干扰物/背景四个 mask 足够；不要 mask 所有物体。

### 6.2 语言反事实

```python
def language_audit(vla, obs, instruction, swap):
    l2 = instruction.replace(swap.old, swap.new)
    base = vla.predict(obs, instruction)
    cf = vla.predict(obs, l2)
    return np.linalg.norm(base - cf)
```

- swap 从账本候选里选：如 red→green，battery→block，top→bottom，first→second。
- 如果 \(S_{lang}\) 接近 0，说明模型不看语言；优先加视觉指认/子目标 prompt，而不是继续调伺服。
- 语言反事实只多一次前向，适合在线子目标边界。

### 6.3 证书与阈值

```json
{
  "task_id": "T06",
  "subgoal": 1,
  "target_id": "block_red",
  "receptacle_id": "slot_1",
  "scene_version": 0,
  "ledger_confidence": 0.91,
  "S_target": 0.184,
  "S_receptacle": 0.121,
  "S_distractor_max": 0.043,
  "S_bg": 0.019,
  "margin": 0.078,
  "S_lang": 0.096,
  "decision": "accept"
}
```

阈值：

- `margin > 0.02`（归一化动作尺度）→ accept。
- `0.0 < margin <= 0.02` → 加/换视觉标记，重跑 PLAN。
- `margin <= 0` → 重绑；仍不行 → 账本目标 + CHUNK-SERVO；目标不可见 → RECOVER。
- `S_lang < 0.01` → 语言条件弱；检查 prompt/标记，不要只调增益。

阈值必须用单任务通道校准；不要从论文数字直接搬。

### 6.4 成本与调度

- 4 masks × 2–4 子目标 = 8–16 次前向/episode；6B/4-step 在 24GB 上约 0.2–0.5s/次 → 2–8s/episode，180s 内可接受。
- 但不能同步塞进 `get_action`；放在子目标边界的安全点，或后台 worker 异步跑。
- 在线默认只跑语言反事实（1 次前向）+ 目标/最大干扰物两个 mask（2 次）；完整 4-mask 用于离线/单任务。
- 审计结果只影响下一个子目标；当前 chunk 不等。

## 7. 子目标验证与人为干扰重绑

### 7.1 expected_effect

每个 subgoal 必须带可几何验证的 `expected_effect`：

| subgoal | expected_effect | 验证 |
|---|---|---|
| pick(block_red) | `grasped(block_red)` | 夹爪闭合 + `r_grasp` <1cm |
| place(block_red, slot_1) | `in(block_red, slot_1)` | 目标在容器 bbox 内 + 可见 |
| stack(bowl_red, bowl_green) | `on(bowl_red, bowl_green)` | z-order + 水平重叠 |
| zip(pencil_case) | `zipped(pencil_case)` | 拉链头位移 >2cm |
| sort(fruit, plate) | `on(fruit, plate)` + `same_color` | 容器/颜色 |
| spell(robot) | `order(letters) == robot` | 字母 id 顺序 |
| pour(bottle, container) | `in(medicine, container)` | 目标/颗粒可见性 + 容器 |

### 7.2 检查与重试

```python
def check_subgoal(subgoal, ledger):
    if subgoal.effect == "in":
        return ledger.objects[subgoal.target].container == subgoal.receptacle
    if subgoal.effect == "on":
        return ledger.relation("on", subgoal.target, subgoal.receptacle)
    if subgoal.effect == "grasped":
        return ledger.grasp_residual(subgoal.target) < 0.01
    if subgoal.effect == "zipped":
        return ledger.zipper_displacement(subgoal.receptacle) > 0.02
    return False
```

- 每个 subgoal 最多重试 2 次；仍失败 → 重新 GROUND/PLAN。
- 重试不能重复抓同一个物体；账本 `completed` 防止重复。
- 步骤分：即使最终失败，完成的子目标能被识别，避免“做了但不算”。

### 7.3 人为干扰重绑

触发：

- `scene_version` 增加（目标/受器 pose 跳变 >2cm、新物体、目标消失）。
- VLA 动作方向与账本目标方向相反（点积 <0）。
- `r_grasp` 突变/滑移；`expected_effect` 超时未达成。

动作：

```text
STOP (safe hold / last legal chunk)
  → RE-GROUND (re-detect, re-track)
  → REVISE (update target/receptacle id, order)
  → PLAN (new subgoal)
  → ACT
```

- 不重启 episode；不要求人重复指令；不继续旧 plan 的剩余 chunk。
- 目标：human 轴 2/10 trials；从 0 恢复到 1 就是 +20pp 单任务，全局 +2pp。
- 如果目标被拿走且不在场景：搜索（转头/移动 base 不允许？先不动 base）→ 找不到则失败退出，节省 180s。

## 8. 可选 DEMO-DIALOGUE LoRA

### 8.1 离线转录

```text
for each episode:
    schema = parse(instruction)
    ledger = build_ledger(episode.frames)
    events = segment_by_gripper_and_contacts(episode)
    for each event:
        subgoal = infer_subgoal(schema, ledger, event)
        transcript.append({
            "instruction": instruction,
            "ledger": summarize(ledger, subgoal),
            "subgoal": subgoal.to_json(),
            "expected_effect": subgoal.effect,
        })
```

- 33k episodes × 2–6 子目标 ≈ 100k–200k 条对话样本；每条形如“指令 + 账本摘要 → 子目标 JSON”。
- 账本摘要只给候选 id/类别/颜色/pose/关系/置信度，不给整图；防止模型背像素。
- 子目标 JSON 是 schema 的子集；输出 128 token 内。

### 8.2 反事实增强

- 交换颜色：red↔green、blue↔yellow；正确 target id 跟着变。
- 移动目标/受器：pose 变，id 不变；训练模型用 pose 而不是位置记忆。
- 加干扰物：同色/同类；正确 target 仍是 schema 指定。
- 改顺序：right-to-left ↔ left-to-right；正确 order 跟着变。
- 删物体：目标不存在 → 输出 `search`/`fail`，不硬抓。

### 8.3 训练与门控

- 只对 WLA VLM 做 LoRA（官方已支持），action head 冻结或小 LoRA；不要从头训。
- 输入：缩小的头/腕图（336×448）+ 账本 JSON + 指令；输出：subgoal JSON。
- 损失：JSON token CE + 可选 target id 分类；不训练检测器。
- 门控：离线 subgoal 准确率 +10pp；真机 binding-heavy +3pp；contact 不掉 >2pp；否则不做。
- 风险：过拟合账本格式；用 20% 任务 held-out + 反事实增强 + 零样本基线。

## 9. 竞赛策略

### 9.1 任务组合

| 组 | 任务 | 主武器 | 目标 |
|---|---|---|---|
| **Binding-heavy** | ColorArrangement、ArrangePlates、StackBowls、SpellRobot、FruitSorting、OrganizeStationery、OrganizePencilCase、ToolboxStorage、PackBag、ConveyorSorting | SCENE-TURN + 视觉指认 + 顺序验证 | +5–10pp |
| **Contact-heavy** | HangCup、DisconnectEthernet、PlugCharger、Unlock、ZipUp、PlugInEthernet、RemovePinnedNote、SyringeWaterTransfer | CHUNK-SERVO + DG-KEYFRAME | +3–8pp |
| **Both** | PackDoll、StoreEarphones、ArrangeTestTubes、PaperCupStacking、StoreCups、StorePaddle、PackPhone、PlacePhotoFrame | SCENE-TURN 选目标/顺序 + CHUNK-SERVO 收尾 | +5pp |
| **Baseline** | FoldTowel、PourOutMedicine、其余变形/长程 | 官方 WLA + 正确 adapter | 不掉点 |

### 9.2 算术

- 32 任务 ×10 = 320 trials；human 轴 64 次（20%）。
- 10 个 binding-heavy 任务各 +8pp → 全局 +2.5pp。
- human 轴 +10pp → 全局 +2.0pp。
- 子目标验证让步骤分 +3 → tie-break 有利。
- 成本：1–3 次 VLM/episode + 5–10Hz 账本；异步 planner 不增加 `get_action` p95。

### 9.3 提交节奏

1. **Baseline**：官方 WLA + 正确 adapter（绝对 EE、pivot 常数、gripper 量纲）；先锁 320 trials 不崩。
2. **SCENE-TURN zero-shot**：账本 + 视觉标记 + 子目标验证；5 个 binding-heavy 单任务 A/B。
3. **Binding Audit**：离线证书验证 margin 与成功/失败相关；在线只语言反事实。
4. **CHUNK-SERVO 合流**：contact-heavy 开 5 步伺服；账本目标做 PBVS。
5. **LoRA（可选）**：前 4 步证明 binding 是瓶颈且零样本不够时才做。

## 10. 实验门 G0–G8

| 门 | 问题 | 通过标准 | 不过怎么办 |
|---|---|---|---|
| **G0** | Adapter 对不对 | 离线回放 100 条：EE 绝对位姿误差 <5mm/0.5°，gripper 相关 >0.9，pivot 与数据集常数一致，无 NaN | 先修 adapter，不做上层 |
| **G1** | 账本准不准 | 5 任务抽检：物体检测/关联 >90%，pose 误差 <2cm，关系准确率 >85%，延迟 <30ms/帧 | 降级为颜色块 + 模板，不追通用检测 |
| **G2** | 审计有没有效 | held-out 上 margin 预测成功/失败 AUC >0.7；成功案例 mask 目标 > mask 干扰物 | 调整 mask/阈值；只保留语言反事实 |
| **G3** | 视觉指认有没有用 | 5 个 binding-heavy 各 10 次 A/B：开标记 +5pp；contact 不掉 >2pp | 改腕图细框/低透明度/只画 target |
| **G4** | 内部对话能不能实时 | 1–3 次 VLM/episode；subgoal 准确率 >80%；单次 <1.5s；`get_action` p95 稳定 | 异步/缓存/缩小输入；降到 1 次 |
| **G5** | 人为干扰能不能重绑 | 模拟移动目标/受器 20 次：恢复 >50%，恢复 <3s | 加 scene_version/重定位；退回 VLA |
| **G6** | 与 CHUNK-SERVO 合流 | 10 任务配对 A/B：成功率 +5pp，步骤分 +5，延迟稳定 | 分任务开关；接触任务只用 servo |
| **G7** | 竞赛合规 | 单模型/单 checkpoint；N 端口隔离；token 正确；320 trials 无崩溃；动作无异常 | 回退 baseline |
| **G8** | LoRA 值不值 | 离线 subgoal +10pp；真机 binding-heavy +3pp；contact 不掉 | 不做 LoRA，保留零样本 |

## 11. 风险与合规

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 账本检测错，标记错目标 | 中 | 高 | 置信度门控；审计；回退 VLA；只用粗定位 |
| 视觉标记反而干扰 VLA | 中 | 中 | 零样本 A/B；腕图/细框/低透明度；可关闭 |
| VLM planner 延迟抖动 | 中 | 高 | 异步；1–3 次/episode；缓存；缩小图；不阻塞 `get_action` |
| 审计太贵 | 高 | 中 | 离线/异步；在线只语言反事实；证书只记不实时跑 |
| 被判定“第二个模型” | 低 | 高 | 只用官方 WLA checkpoint；账本是确定性 CV；无第二个学习检测器；文档写清 |
| 人为干扰不可预测 | 高 | 中 | `scene_version` + 重定位 + 重绑；不重启 episode |
| 顺序任务状态机卡死 | 中 | 中 | 超时/重试上限；失败回退 VLA；步骤分保底 |
| 夹爪/pivot 量纲错 | 中 | 高 | G0 先验；用 `example_env.py` 和数据集 stats 校准 |
| 多端口共享 GPU 阻塞 | 中 | 高 | 异步批处理；每端口独立队列；超时降级 |

**单模型合规**：

- 只有一份 WLA 权重；planner 是同一 checkpoint 的 VLM（可 LoRA，属于同一模型）。
- 账本用 SGBM/RANSAC/HSV/ORB/匈牙利匹配，全是经典算法，无训练权重；不是“第二个模型”。
- 伺服是确定性控制器；不是学习残差策略。
- 每端口独立 `reset()`；账本/对话/plan 状态不跨端口共享；共享的只有模型权重。
- 不做跨 episode 在线学习、不做测试时训练、不下载隐藏测试数据。
- 如果官方对“模型”作最宽解释，账本/伺服仍应作为“确定性控制器”在提交说明中披露，不隐藏。
