# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配交互消歧闭环」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「场景落地」×「任务分解」）

> R69 把不确定性一分为二，给「问」配上了流匹配的嘴和 VoI 的脑子，交付了一个漂亮的理论闭环。但它交付的是**一个定理，不是一套能部署的系统**：单一 π_θ、单一 trunk、单一标定环、单一交互预算、单一证书，默认所有部件同源、同标定、同 ODD。真实落地恰好相反——感知来自供应商 A，机械臂来自 B，安全 PLC 来自 C，问句来自一个不能微调的 LLM，场景从仓库换到厨房，任务从「抓取」拆成「找—够—抓—放—验」。**你无法部署一个定理，你只能部署一个任务。**
>
> 于是本轮两个灵感不是工程收尾，而是研究问题的转移：
> - **任务分解**改变的是「保证的对象」：从「策略在状态上的行为」变成「瓦片之间的契约」。分解不是打包，它引入了一类全新的实体——**接缝（seam）**。
> - **场景落地**改变的是「验收的单位」：从平均回报变成**带风险预算的场景清单 + 可统计检验的调试门**。Demo 不是落地，通过验收才是。
>
> 核心命题：**把 FLUID-RAS 分解成携带契约的能力瓦片（skill tile），用 assume-guarantee 组合把安全局部化，用不确定性台账给接缝定价，用任务级 VoI 把交互摊销到整张任务图，用序贯检验做场景调试门；只有当「瓦片收益 > 接缝税 + 协调开销」时才分解。** 命名 **TESSERA-RAS**（Task-dEcomposed Scenario-grounded Safety with Evidence-carrying Runtime Assurance）——tessera 是马赛克里的一块瓦片：每块自带契约，拼起来才是场景。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**这套东西拆开后，谁来为接缝负责**」。

## 0. 直觉与动机

**灵感 1（任务分解 → 保证的对象从行为变成契约）**
直觉：R69 的定理 16「FLUID 严格包含 R68」是对一个单体策略说的。一旦把闭环切成 5 个瓦片，定理不会自动成立，而是**变成 5 组前提**：上游的 post 必须蕴含下游的 pre；共享的 z_t 必须仍同分布；交互预算必须仍全局一致。分解没有消灭不确定性，只是把它从「模型里」搬到了「接口上」。所以分解的第一性原理不是「模块化好」，而是**守恒**：不确定性可以转移、可以转化（epistemic→aleatoric）、可以被支付，但不能凭空消失。任何让 U 在接缝处归零的分解，都是在账本上造假。

**灵感 2（场景落地 → 验收是统计推断，不是演示）**
直觉：场景 = (环境, 任务, 约束, 参与者, 验收谓词)。落地不是「在目标场景跑一遍没坏」，而是「以置信度 1−α 断言：在 ODD 内，风险 ≤ ρ」。这天然是一个序贯假设检验问题：每跑一个场景攒一个 e-value，证据够了才允许部署。Demo 选了 3 个漂亮场景通过，与统计上接受 H0 是两件事——前者极易被 Goodhart，后者需要留出场景、需要 ODD 覆盖、需要可证伪的失败判据。落地研究的核心产出因此不是又一个模块，而是**一张可执行的场景清单 + 一道会拒绝的调试门**。

**灵感 3（对偶 → 分解同时带来摊销收益与洗白风险）**
直觉：任务图让「问」可以提前。单体反应式策略只在歧义发生的当下问；任务图知道「三步之后要抓」，于是可以在「找」的阶段先问清「抓哪个」，一次交互摊销给多个下游瓦片——这是分解的正收益（interaction amortization）。但同一机制也是攻击面：在 A 场景获得的一条证据，被无声复用到 B 场景，就是**证据洗白（evidence laundering）**。摊销与洗白是同一枚硬币：出处（provenance）、作用域（scope）、时间（time）必须随证据一起流动，跨信任边界必须重新取证或显式降权。

**灵感 4（何时该分解 → 近可分解性给出定量判据）**
直觉：Herbert Simon 的「近可分解系统」说，复杂系统之所以可被理解，是因为子系统间的耦合弱于子系统内的耦合。分解不是免费的：跨切口的互信息越大，接缝税越高。于是「要不要分解」不该靠架构品味，而该有判据：**当异构性收益 + 独立认证收益 + 交互摊销收益 > 接缝税 + 协调开销时，分解才值得**。这既是设计准则，也是可做实验的假设（E304/E305）。

**灵感 5（R69 是 R70 的一张瓦片 → 新层仍是旧层的退化）**
直觉：延续 R69 的理论姿态：TESSERA 必须是 FLUID 的严格泛化，而不是并列替代。最干净的做法是让「不分解」= 只有一个瓦片：此时台账无缝、契约退化为恒真、任务级 VoI 退化为单体 MINT，整个 TESSERA 逐指令退化为 R69。这样每加一层分解，都能回答「它比 R69 多做了什么、代价多少、何时该退回」。

## 1. 形式化定义（增量：定义 310–325）

**定义 310（场景清单 S / ODD）** S = (E, T, C, P, Ψ, ρ, α)。E 环境族、T 任务族、C 约束、P 参与者（人 / 其他机器人）、Ψ: 轨迹×(E,T,C,P) → {0,1} 场景验收谓词、ρ 风险预算、α 调试显著性。场景落地 ⇔ 在 S 上以置信度 1−α 接受「风险 ≤ ρ」。

**定义 311（任务分解图 D）** D = (V, E_D, κ)，V 为能力瓦片，E_D ⊂ V×V 为带方向的数据 / 控制依赖，κ: E_D → K 为边契约。D 默认无环；存在环时显式时间展开为无环图。

**定义 312（能力瓦片 v）** v = (π_v, Safe_v, U_v, cert_v, fallback_v, io_v)。π_v 局部策略（可为 R69 的 FLUID 子策略，也可为传统控制器）；Safe_v 局部安全包络；U_v 局部不确定性模型；cert_v 本地证书模板；fallback_v ∈ {R68-保守, 定点保持, 安全停}；io_v 输入输出类型（含单位、坐标系、时间戳语义）。

**定义 313（瓦片契约 K_v）** K_v = (Pre_v, Post_v, Inv_v, U_budget_v, cert_level_v, scope_v, deadline_v)。Pre 是上游必须提供的假设；Post 是向下游承诺的保证；Inv 是瓦片内不变式；scope_v 规定本地证书 / 证据的有效范围（场景 / 坐标 / 时间 / 本体）；deadline_v 是该瓦片 P99 时间预算。契约良构 ⇔ Pre 可由环境保证或上游 Post 蕴含，且 Inv 在 π_v 下归纳成立。

**定义 314（组合算子 ⊕ 与精化 ≼）** D1 ⊕ D2 在共享接口上做串行 / 并行组合；D 精化单体策略 π（记 D ≼_ε π）⇔ 存在仿真关系 R，使 D 的任一可达联合状态在 ε 内被 π 的行为包含，且契约组合保持安全。TESSERA 要求 D ≼_ε π_FLUID。

**定义 315（不确定性台账 L 与接缝税 τ_seam）** L 为每个瓦片记录 (U_ale, U_epi, 置信, 证据出处)，并为每条边定义转移函数 T_e（含 Lipschitz 常数 L_e 与接口失配 ε_e）。组合界：U_comp ≤ Σ_v U_v + Σ_e L_e ε_e + H_cut，其中 H_cut 为跨切口条件熵。接缝税 τ_seam := U_comp − Σ_v U_v ≥ 0，是分解相对单体的风险增量。**台账不变式：任何瓦片的 U 只能被显式支付 / 转化 / 降级，不得在接口处归零。**

**定义 316（任务级 VoI 调度）** 交互预算 b 分配在 D 上：max_{g_1..g_m} E[Σ_v ΔH_v(g)] s.t. Σ c(g_i) ≤ b，且交互必须早于其受益瓦片的 deadline。一次交互可消解多个下游瓦片的歧义（摊销），但只能按其 scope 记账。

**定义 317（证据出处与信任边界）** 证据 e = (value, source, scope, t, tile_id, sig)。跨信任边界（人→机、供应商 A→B、仿真→实机）复用时必须重新取证或显式降权；禁止把「A 场景的答案」直接当作「B 场景的 Post」。违例称证据洗白。

**定义 318（契约变异测试 / 接缝故障模型）** 对每条边注入变异 μ_e ∈ ℳ_seam：单位 / 坐标系错、时间戳倒序、缺失字段、静默截断、延迟抖动、范围外值、语义漂移。接缝故障检出率 = 被契约监视器拦截的 μ_e 比例。

**定义 319（调试门 / 场景验收）** 序贯 e-process：每场景产出 e-value，H0: risk ≤ ρ。累积 e-value ≥ 1/α 时拒绝 H0（准予部署）；否则继续采样或拒绝部署。要求留出场景集与 ODD 覆盖证明，禁止在调试集上调参后复用。

**定义 320（部署证书 J_TESSERA）** J_TESSERA = (⨁_v J_v, composition_proof_hash, L_digest, τ_seam, coverage_map, commissioning_record, version_lock)。Valid ⇔ 每个 J_v 有效 ∧ 组合精化成立 ∧ τ_seam ≤ τ_max ∧ 调试门通过 ∧ 版本锁一致。

**定义 321（降级阶梯）** L0 全 TESSERA → L1 关闭某瓦片的 MINT → L2 该瓦片 fallback_v（R68 保守）→ L3 安全停。要求单调：级别升高时风险不增、能力不增；切换含驻留时间与迟滞，禁止抖动。

**定义 322（ODD 运行时监控）** 在线判据 o_t ∈ ODD(S)；越界即升到 L3 或请求人类接管。覆盖度 cov(S) 为调试场景对 ODD 的测度覆盖，未覆盖区域的风险断言无效。

**定义 323（可移植性契约）** 瓦片接口以任务语义（而非本体坐标）定义；同一 D 可在不同本体上实例化，只需满足 io_v 与 deadline_v。可移植性 ⇔ 换本体后契约仍良构且 τ_seam 不显著上升。

**定义 324（分解判定准则）** 分解收益 Δ = (异构性收益 + 独立认证收益 + 交互摊销收益) − (τ_seam + 协调 / 通信开销 + 调试开销)。仅当 Δ > 0 且 τ_seam ≤ τ_max 时分解；否则保持单体 FLUID。R69 恰为「D 只有一张瓦片」的边界。

**定义 325（Goodhart 防护）** 调试集 D_fit、留出集 D_hold、红队集 D_red 三分离；验收只能在 D_hold 上做，D_red 用于主动搜索接缝与 ODD 边界；任何在 D_fit 上提升而 D_hold 不提升的改动视为过拟合，拒绝合入。

## 2. 关键算法骨架

```python
# IP-264 Tile SDK：能力瓦片 + 本地兜底 + 契约自检
class Tile:
    def __init__(self, pi, safe, u_model, fallback, contract):
        self.pi, self.safe, self.u = pi, safe, u_model
        self.fallback, self.K = fallback, contract

    def step(self, x, ctx):
        assert self.K.Pre.check(x, ctx), "upstream violated precondition"
        a = self.pi.act(x, ctx)
        a = self.safe.project(a)                    # 局部包络，永不外包
        assert self.K.Inv.check(x, a), "invariant broken"
        return a, self.K.Post.emit(x, a), self.u.export()

# IP-265 DAG Compiler：场景 -> 任务图（离线；契约由规范 + 示教推断）
def compile_task_graph(scenario, skill_lib, demos):
    spec = decompose(scenario.task)                 # 任务语义分解
    V    = match_skills(spec, skill_lib)            # 选择/组合瓦片
    E    = infer_edges(V, demos)                    # 数据/控制依赖
    for v in V: v.K.Pre, v.K.Post = infer_contract(v, demos)
    D = TaskDAG(V, E)
    assert is_acyclic(D) and contracts_well_formed(D)
    return D

# IP-266 契约运行时监视：前条件/后条件/不变式/时限
def contract_monitor(D, trace):
    for (u, v, e) in trace:
        if not D.post(u).implies(D.pre(v)): return Violation("seam", u, v)
        if not D.K[v].deadline.met(e):       return Violation("deadline", v)
    return Ok()

# IP-267 不确定性台账：接缝税传播（守恒，不归零）
def propagate_uncertainty(D, U_local, edges):
    U = dict(U_local)
    for (u, v, T_e) in edges:                       # 拓扑序
        U[v] = merge(U[v], T_e(U[u]))               # 含 L_e * eps_e
    tau = sum(U.values()) - sum(U_local.values())   # τ_seam >= 0
    assert tau >= 0 and ledger_conserved(D, U)
    return U, tau

# IP-268 任务级 VoI：交互摊销 + 预算分配（DAG 上自适应次模贪心）
def schedule_interactions(D, ambiguity, budget):
    plan = []
    while budget.left > 0:
        g = argmax_gain(D, ambiguity, plan, budget)  # gain = 下游共享 ΔH - cost
        if g is None or g.gain <= 0: break
        plan.append(g); budget.charge(g)
        ambiguity = apply_evidence_scope(ambiguity, g)   # 只在其 scope 内生效
    return plan

# IP-269 证据出处：跨信任边界必须重新取证
def accept_evidence(e, target_tile, target_scope):
    if e.scope.covers(target_scope) and e.tile_id == target_tile.id:
        return e.value
    return require_reverification(e)                # 否则降权/重取，禁止洗白

# IP-271 调试门：序贯 e-process（会拒绝才算门）
def commissioning_gate(e_values, rho, alpha):
    log_e = 0.0
    for z in e_values:
        log_e += log_e_value(z, rho)                # H0: risk <= rho
        if log_e >= log(1.0 / alpha): return "DEPLOY"
    return "REJECT_OR_CONTINUE"                     # 证据不足不得上线

# IP-274 TESSERA 运行时：契约 -> 台账 -> 任务 VoI -> 降级 -> 证书
def TESSERA_round(D, obs, budget):
    lvl = D.odd_monitor.level(obs)
    if lvl >= 3: return safe_stop()
    states = {v: D.tiles[v].step(obs, D.ctx) for v in topo_order(D)}
    if contract_monitor(D, states) is Violation("seam", u, v):
        return D.ladder.escalate(v)                 # 单调降级，不猜
    U, tau = propagate_uncertainty(D, export_U(states), D.edges)
    for g in schedule_interactions(D, ambiguity(states), budget):
        answer = D.cia.execute(g)                   # 仍受 R69 认证 + 证据纪律
        states = D.update_with_scope(states, answer)
    A = assemble_actions(D, states)
    D.cert.append(J_TESSERA(D, U, tau, D.commissioning))
    return A
```

## 3. 推导

**引理 19（assume-guarantee 组合保持局部安全）** 若 D 无环、每条边契约良构、且环境保证 G_env 蕴含每个源瓦片的 Pre，则所有瓦片 Inv 的合取在 D 的整个执行上归纳成立；因而全局安全性可由 Σ_v 局部证明 + Σ_e 契约检查推出，无需重新证明单体策略。要点：分解把「证明一个大的」换成「证明许多小的 + 检查接缝」；接缝检查器本身必须被独立验证，否则它只是把信任从模型搬到了检查器。

**引理 20（接缝税下界 / 不确定性守恒）** 对任意切口 (S, S̄)，设接口为 Y，跨切口互信息为 I(X_S; X_S̄ | Y)。则任何在接口处丢弃该互信息的分解满足 τ_seam ≥ c·I(X_S; X_S̄ | Y) − ε_m，其中 ε_m 为接口建模误差，c 由任务损失对状态扰动的 Lipschitz 常数给出。系：**强耦合任务（互信息大）不可免费分解**；分解只在「近可分解」区域划算，这与 Simon 的判据一致，并把它变成可测量的量（E304）。

**引理 21（任务级 VoI 的摊销与次模性）** 在 DAG 的先序约束下，交互的期望熵减对「已选交互集合」自适应次模；贪心调度达到 (1−1/e) 近似。一次交互若其 scope 覆盖 k 个下游瓦片，则摊销收益 ≤ Σ_{v∈scope} ΔH_v，等号当且仅当各瓦片歧义源相同且证据可合法复用。系：摊销是分解的正收益，但被定义 317 的出处纪律严格上界——**scope 越宽收益越大，洗白风险也越大**，二者必须同时优化。

**定理 18（TESSERA 保守精化 FLUID）** 在 A99–A102（契约良构、台账守恒、降级单调、调试门有效）下，若 D ≼_ε π_FLUID，则部署系统的场景风险 ≤ R69 风险 + τ_seam；当 D 只有一张瓦片时 τ_seam = 0，TESSERA 逐指令退化为 R69。因此 R69 是 TESSERA 在「不分解」边界上的退化：分解维度上严格泛化，安全侧不让步。

**定理 19（调试门的统计有效性）** 若 e-value 在 H0 下满足 E[e] ≤ 1 且场景采样与部署分布一致，则序贯调试门的误部署率 ≤ α；在 ODD 覆盖不足或分布偏移 TV 距离为 δ 时，风险断言退化为 ρ + δ·B（B 为风险有界常数）。系：**验收证书只在覆盖图内有效**；把「通过验收」当成「处处安全」是统计上的越界使用。

**定理 20（降级单调与无突变）** 任一米片契约违例触发阶梯升级；若每级 fallback 的风险不大于其前级且切换含驻留 / 迟滞，则升级过程风险单调不增，且不存在安全包络外的瞬态。继承 R69 定理 17（交互安全与无突变）的换装不变式。

## 6. 本轮最大风险

**一句话**：TESSERA 的最大风险不是某张瓦片失败，而是**所有瓦片都通过了各自的验收、接缝却无人负责**——不确定性被「守恒」地记进了台账，但台账本身由人定义、由同一批人验收，接缝税一旦被系统性低估，系统就会在纸面上更可信、在现实中更脆弱；再叠加场景验收的 Goodhart，团队会优化「通过测试」而不是「降低风险」。

**次级风险与缓解**：
1. **契约是自证循环**（检查器与被检查者同源）→ 引理 19 要求接缝检查器独立实现 + E303 变异测试；

3. **证据洗白跨场景放大** → 定义 317 出处 / scope / 签名 + E313 红队；
4. **验收过拟合（Goodhart）** → 定义 325 三集分离 + E311 留出与红队；
5. **分解收益为负仍强行拆** → 定义 324 判定准则 + E314/E315 成本核算，默认单体 R69。

## 2. 形式化定义（要点版）

**定义 310（场景清单 / ODD）** 场景是七元组 `(E,T,C,P,Ψ,ρ,α)`；落地 = 以置信度 `1−α` 接受「风险 ≤ ρ」，不是「跑一遍没坏」。

**定义 313（契约）** `K_v=(Pre,Post,Inv,U_budget,cert_level,scope,deadline)`；良构 ⇔ Pre 被环境或上游 Post 蕴含，Inv 在 π_v 下归纳成立。

**定义 314（组合与精化）** `⊕` 在共享接口上串/并行组合；`D ≼_ε π_FLUID` 用仿真关系定义；TESSERA 要求部署图精化 R69 单体策略。

**定义 315（台账与接缝税）** 逐瓦片记 `(U_ale,U_epi,置信,出处)`，逐边传播 `L_e` 与接口失配 `ε_e`；`U_comp ≤ Σ U_v + Σ L_e ε_e + H_cut`，`τ_seam := U_comp − Σ U_v`。**U 只能支付/转化/降级，不得在接口归零。**

**定义 316（任务级 VoI）** 预算 b 在 D 上分配，最大化下游共享熵减；交互必须早于受益瓦片 deadline；摊销只能按 scope 记账。

**定义 317（证据出处）** 跨信任边界复用必须重新取证或显式降权；禁止把 A 场景答案直接当 B 场景 Post（洗白）。

**定义 318（接缝变异测试）** 对边注入单位/坐标系/时序/缺失/截断/抖动/越界/语义漂移变异，测检出率。

**定义 321–323（降级 / ODD / 可移植）** L0→L3 单调降级 + 驻留/迟滞；在线 ODD 监控，越界升 L3；接口以任务语义定义，同一 D 可跨本体实例化。

## 3. 关键算法伪代码

```python
# IP-264 Tile SDK：局部策略 + 局部安全 + 本地兜底 + 契约自检
class Tile:
    def step(self, x, ctx):
        assert self.K.Pre.check(x, ctx)
        a = self.safe.project(self.pi.act(x, ctx))      # 安全包络，永不外包
        assert self.K.Inv.check(x, a)
        return a, self.K.Post.emit(x, a), self.u.export()

# IP-265 DAG Compiler：场景 -> 任务图（离线）
def compile_task_graph(scenario, skill_lib, demos):
    spec = decompose(scenario.task)
    V, E = match_skills(spec, skill_lib), infer_edges(demos)
    for v in V: v.K.Pre, v.K.Post = infer_contract(v, demos)
    D = TaskDAG(V, E)
    assert is_acyclic(D) and contracts_well_formed(D)
    return D

# IP-267 台账：接缝税传播（守恒，不归零）
def propagate_uncertainty(D, U_local, edges):
    U = dict(U_local)
    for (u, v, T_e) in topo_edges(edges):
        U[v] = merge(U[v], T_e(U[u]))                  # 含 L_e * eps_e
    tau = sum(U.values()) - sum(U_local.values())      # τ_seam >= 0
    assert tau >= 0 and ledger_conserved(D, U)
    return U, tau

# IP-268 任务级 VoI：交互摊销 + DAG 预算分配（自适应次模贪心）
def schedule_interactions(D, ambiguity, budget):
    plan = []
    while budget.left > 0:
        g = argmax_gain(D, ambiguity, plan, budget)    # 下游共享 ΔH - cost
        if g is None or g.gain <= 0: break
        plan.append(g); budget.charge(g)
        ambiguity = apply_evidence_scope(ambiguity, g) # 只在其 scope 内生效
    return plan

# IP-269 证据出处：跨信任边界必须重新取证
def accept_evidence(e, target_tile, target_scope):
    if e.tile_id == target_tile.id and e.scope.covers(target_scope):
        return e.value
    return require_reverification(e)                   # 否则降权/重取，禁止洗白

# IP-271 调试门：序贯 e-process（会拒绝才算门）
def commissioning_gate(e_values, rho, alpha):
    log_e = 0.0
    for z in e_values:
        log_e += log_e_value(z, rho)                   # H0: risk <= rho
        if log_e >= log(1.0 / alpha): return "DEPLOY"
    return "REJECT_OR_CONTINUE"                        # 证据不足不得上线

# IP-274 TESSERA 运行时：契约 -> 台账 -> 任务 VoI -> 降级 -> 证书
def TESSERA_round(D, obs, budget):
    if D.odd_monitor.level(obs) >= 3: return safe_stop()
    states = {v: D.tiles[v].step(obs, D.ctx) for v in topo_order(D)}
    if contract_monitor(D, states) is Violation("seam", u, v):
        return D.ladder.escalate(v)                    # 单调降级，不猜
    U, tau = propagate_uncertainty(D, export_U(states), D.edges)
    for g in schedule_interactions(D, ambiguity(states), budget):
        states = D.update_with_scope(states, D.cia.execute(g))
    D.cert.append(J_TESSERA(D, U, tau, D.commissioning))
    return assemble_actions(D, states)
```

## 4. 推导

**引理 19（assume-guarantee 组合保持局部安全）** 若 D 无环、边契约良构、环境保证 `G_env` 蕴含每个源瓦片 Pre，则所有 `Inv` 的合取在 D 的整个执行上归纳成立；全局安全 = Σ 局部证明 + Σ 接缝检查。系：检查器必须独立实现，否则只是把信任从模型搬到检查器。

**引理 20（接缝税下界 / 不确定性守恒）** 对任意切口 `(S,S̄)`、接口 Y，跨切口互信息 `I(X_S;X_S̄|Y)` 越大，任何丢弃它的分解的 `τ_seam` 越大：`τ_seam ≥ c·I(X_S;X_S̄|Y) − ε_m`，c 由任务损失对状态扰动的 Lipschitz 常数给出。系：强耦合任务不可免费分解；分解只在「近可分解」区域划算（把 Simon 判据变成可测量，E304）。

**引理 21（任务级 VoI 摊销与次模性）** DAG 先序约束下，期望熵减对已选交互集合自适应次模，贪心达 `(1−1/e)`；一次交互 scope 覆盖 k 个下游瓦片时摊销收益 ≤ `Σ_{v∈scope} ΔH_v`，等号当且仅当歧义源相同且证据可合法复用。系：scope 越宽收益越大、洗白风险也越大，二者必须联合优化。

**定理 18（TESSERA 保守精化 FLUID）** 在 A99–A102（契约良构、台账守恒、降级单调、调试门有效）下，若 `D ≼_ε π_FLUID`，则场景风险 ≤ R69 风险 + `τ_seam`；当 D 只有一张瓦片时 `τ_seam=0`，逐指令退化为 R69。R69 是 TESSERA 在「不分解」边界上的严格退化。

**定理 19（调试门统计有效性）** 若 e-value 在 H0 下 `E[e]≤1` 且采样分布与部署一致，序贯调试门误部署率 ≤ α；ODD 覆盖不足或分布偏移 TV 距离为 δ 时，风险断言退化为 `ρ + δ·B`。系：验收证书只在覆盖图内有效，把「通过验收」当「处处安全」是越界使用。

**定理 20（降级单调与无突变）** 任一米片契约违例触发阶梯升级；若每级 fallback 风险不大于前级且切换含驻留/迟滞，则升级过程风险单调不增，无安全包络外瞬态。继承 R69 定理 17（交互安全与无突变）的换装不变式。

## 7. 本轮最大风险

**一句话**：TESSERA 的最大风险不是某张瓦片失败，而是**所有瓦片都通过了各自的验收、接缝却无人负责**——不确定性被「守恒」地记进台账，但台账由人定义、由同一批人验收，接缝税一旦被系统性低估，系统就会在纸面上更可信、在现实中更脆弱；再叠加场景验收的 Goodhart，团队会优化「通过测试」而不是「降低风险」。

**次级风险与缓解**：契约自证循环（接缝检查器独立实现 + E303 变异测试）；接缝税低估/台账造假（定义 315 守恒不变式 + E304 校准 + 审计抽样）；证据洗白跨场景放大（定义 317 出处/scope/签名 + E313 红队）；验收过拟合（定义 325 三集分离 + E311）；分解收益为负仍强行拆（定义 324 判定准则 + E314/E315 成本核算，默认单体 R69）。
