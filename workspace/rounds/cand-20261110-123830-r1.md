# 第 44 轮（新循环第 4 轮） · Fail-Recover × Concurrent-Reasoning：从「故障即降级」到「恢复即再认证」的可验证恢复闭环（四层架构 v9）

> 承接第 43 轮 v20（Persona-Cert × Concurrent-Cert）。v20 自陈最大风险是「共形条件覆盖被欺骗 + 多用户契约空集」，但它还压着一个更深的单点假设：**(H1) 故障只以「单调降级 + 最后整链熔断回退 v19」处理**——系统没有「恢复」的一等语义，降级不可逆，恢复等于推倒重来；**(H2) 并发推理被假定为「各分支 fail-stop 且相互独立」**——真实边缘端会 timeout、崩溃、返回错值、共享传感器相关失效，且并行分支的证书会互相污染恢复后的状态。本轮灵感词「失败恢复」「并发推理」精确命中这两个假设：**失败恢复**迫使我们把「恢复」从异常处理提升为证书代数的一部分（恢复不是还原旧信任，而是从受证基线重新挣得信任）；**并发推理**迫使我们把并发从「并行提速」重解释为「恢复的冗余资源」——存活分支既是证据，也是恢复期必须被隔离的污染源。二者耦合处是本轮真正的新问题：**恢复风暴 × 相关失效**会让「同时重认证」既拖垮实时性、又让陈旧检查点在 epoch 之间互相穿透。

## 0. 直觉与动机

**灵感 1（失败恢复 → 「信任不能回滚，只能重新挣得」）**：一次 VLM 超时或几何求解器发散后，最诱人的做法是从上一个检查点「恢复」旧证书。但这恰恰最危险：旧证书的 soundness 依赖故障前的世界状态与租约，恢复后世界已变、故障原因可能仍在。因此提出**再认证式恢复（re-certification, not restoration）**：永不重放旧信任；恢复协议只能从一个**静态预认证的安全回退证书 C⊥**（safe-hold / 最小可行人格）出发，在 epoch 隔离下重新挣得能力。恢复因此有两条硬约束——**soundness（恢复全程只能在 C⊥ ∪ 已重证子集内动作）**与 **liveness（有界时间内重证出 ≥k 个关键能力）**。一句话：**降级可以不问原因，升级必须重新持证。**

**灵感 2（并发推理 → 既是冗余，也是污染）**：并发分支天然提供冗余：b 路独立认证同一决策，少数分支崩溃/超时可由存活分支遮蔽；但并发也制造两类新故障——**相关失效**（共享相机/时钟/地图，一处坏全坏）与**值故障**（分支返回一个「看起来 sound 但违反全局不变式」的证书）。因此对并发证书不能投票取多数（多数也可能一起错），只能**取交集保 sound、取最高分保可用**，并用交叉校验剔除值故障。更关键的是：故障后**存活分支的中间状态可能已被失败分支写脏**，恢复必须穿过一道 **epoch 恢复屏障**，只接受 epoch ≥ 最后提交点的快照，否则恢复即污染。

**灵感 3（耦合 → 恢复风暴与恢复代数）**：个性化 + 并发把「一次故障」放大成「一片故障」：多用户同时切换、租约成批过期、HI 模式反复切换，会触发**恢复风暴**——大量任务同时重认证，算力被恢复自身吃光，MTTR 超过安全回退的续航，形成「越恢复越不安全」的正反馈。对策是把恢复本身当作一类带关键级与预算的实时任务，并给恢复算子一个可组合的小代数（checkpoint / isolate / re-certify / merge），要求幂等、不透支、写集不相交时可交换。四层架构由此从 v8 的「人格 × 并发证书层」升级为 v9 的「人格 × 并发 × **恢复**证书层」。

**耦合升级**：CRR（认证恢复运行时）提供回退证书、epoch 屏障与有界恢复调度；FTCC（容错并发证书）把并发分支变成「可交叉校验的冗余证据」；RV（恢复验证器）在仿真里注入崩溃/超时/值故障/相关失效与交错，把反例回灌 CKB 与 SCV。v9 = v8 的全部层级 + 一层「恢复正确性」，不推倒任何既有层级。

## 1. 形式化定义（增量：定义 44–50）

**定义 44（故障模型与恢复事件）**：任务族 T 上的故障类型 F = {crash, omission/timeout, value, correlated}。系统状态 s = (K, L, I)，K 为证书库、L 为租约表、I 为证书不变式。恢复事件 e = (i, φ, ε) 表示任务 i 在 epoch ε 发生类型 φ 的故障。**相关失效**：若故障集 F_d 共享同一硬件/传感器依赖 d（相机、时钟、地图、供电），则 P(F_d 全坏 | d 坏) = 1，独立冗余假设在该组内失效，冗余度按依赖分组而非按进程计数。

**定义 45（恢复基线与再认证）**：**安全回退证书** C⊥ ⊆ C_global 是离线静态认证、仅依赖最简传感器与硬件看门狗的最小能力集（安全停靠 / 保持 / 降速）。**再认证式恢复**：故障后系统只在 C⊥ 内动作，恢复协议 R 经「隔离 → 回滚到提交点 → 重新评估 → 合并」产出 C′ ⊆ C_global；在 C′ 签发前，任何故障前证书 K 一律作废，不得用于守卫。**恢复单调性（受限）**：C′ 不要求 ⊇ 故障前能力；只要求 C′ 中每个谓词都经过一次故障后的独立验证。**关键点**：C⊥ 必须由独立于故障推理栈的通道认证，否则恢复循环引用自身。

**定义 46（恢复的 soundness 与 liveness）**：恢复协议 R 是 (T_r, k)-可恢复的，当且仅当：
(1) **Soundness**：恢复全程每个动作 a_t 满足 a_t ∈ C⊥ ∪ (⋃ 已重证 C′)，绝不使用作废证书；
(2) **Bounded liveness**：从任意故障事件起，T_r 内到达某状态使 ≥k 个关键能力被重证；
(3) **Non-contamination**：C′ 的证书不得依赖任何被故障任务在最后有效 epoch 之后写入的变量（写集隔离，复用定义 40 的 rely-guarantee）。
Soundness 与 liveness 的张力即恢复的核心权衡：C⊥ 越大越易活但不安全，越小越安全但可能不可行。

**定义 47（Epoch 恢复屏障与恢复线性一致性）**：证书库维护单调 epoch，**提交点** = 最近一次全量一致的证书快照。**恢复屏障**：任务恢复后只能读 epoch ≥ e_commit 且前后 epoch 一致的快照（seqlock / 双缓冲）；若只能读到更旧快照，必须继续在 C⊥ 内动作并重试。**恢复线性一致性**：存在一个线性化点，使所有恢复读看到的是「故障前最后提交」或「之后某个一致提交」之一，绝无中间撕裂态。**命题**：epoch 屏障 + 提交点快照 ⟹ 恢复读不返回污染状态；否则必须单调降级而非「尽力读取」。

**定义 48（容错并发证书合成 FTCC）**：对同一决策有 b 个独立分支，有效分支集 V = {j : c_j valid}，用交叉校验剔除值故障后得 V\* ⊆ V。**安全可采纳集** A_safe = ⋂_{j∈V\*} A_j（交集保 sound：交集内的动作对所有存活有效证书都可采纳；并集会放行单分支误判，故不可用）。**一致选择** a\* = argmax_{β_j : a ∈ A_j, A_j ⊆ ...} score(β_j)，且约束 a\* ∈ A_safe ∩ C_u。**法定人数**：若 |V\*| < q_min（如 2），判定不可认证 → C⊥ 或协商。**命题（值故障可检测性）**：若值故障分支的证书存在动作 a ∈ A_j 使 a ∉ C_global 或 a ∉ ⋂_{l≠j} A_l，则交叉校验可检出；检测不到的值故障只能靠独立冗余降低概率、不能消除——这是本层的诚实边界。

**定义 49（恢复预算与有界恢复调度）**：恢复任务带关键级 κ_r 与预算 B_r；恢复预算用令牌桶在窗口 W 内封顶，防止恢复风暴。**定理（有界恢复）**：若 (a) 恢复期内 C⊥ 可持续保证安全动作；(b) 窗口 W 内所有恢复任务 WCET 之和 ≤ B_r；(c) 安全监控恢复优先级最高且预算硬隔离（沿用定义 42 的调度契约），则任意故障风暴下 MTTR ≤ T_r，且安全监控不因恢复负载错过截止期。恢复任务与在线任务共用定义 40 的 rely-guarantee，恢复写集必须与在线安全谓词不相交。

**定义 50（恢复算子代数）**：定义算子 checkpoint: S→S、isolate_i: S→S（封锁任务 i 写集）、recert: S→S、merge: S×S→S。**算子律**：(L1) 幂等：recert∘recert = recert；(L2) 不透支：isolate_i∘recert 后的能力 ⊆ C_global；(L3) 可交换性：若写集 W_i ∩ W_j = ∅，则 isolate_i∘isolate_j = isolate_j∘isolate_i，恢复可并行；(L4) 受限期单调：同一 epoch、同一故障上下文下，若 C_a ⊆ C_b 则 recert(C_a) ⊆ recert(C_b)。**跨 epoch 单调性不成立**——这是恢复代数最脆弱处，也是 E97 要专门打的红线。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-60 CERTIFIED-RECOVERY-RUNTIME（认证恢复运行时 CRR）
1. **安全回退证书 C⊥ 编译与守护**：静态、只依赖最简传感器 + 硬件看门狗，独立于故障推理栈认证，作为恢复期唯一放行基线。
2. **checkpoint / epoch 双缓冲 + 恢复屏障**：提交点快照 + seqlock 前后 epoch 校验，拒撕裂读、拒陈旧读。
3. **恢复预算令牌桶 + 混合关键级恢复调度**：恢复任务按 κ_r 排序，安全监控恢复最高且预算硬隔离；风暴时只保关键恢复、其余排队。
4. **再认证流水线**：隔离 → 回滚 → 重证 → 合并四步可审计，每次恢复留痕（故障类型、epoch、重证能力集、耗时）。

### 2.2 IP-61 FAULT-TOLERANT-CONCURRENT-CERT（容错并发证书 FTCC）
1. **相关失效感知的冗余分组**：同一硬件/传感器依赖的分支只计一份冗余度，避免「伪冗余」。
2. **证书交叉校验剔除值故障**：用 C_global 与分支两两交集检查可疑证书，法定人数不足即拒绝。
3. **交集保 sound 的合成选择器**：复用 CCR 的租约、关键级、单调选择，只在 A_safe ∩ C_u 内取最高分。
4. **恢复感知分支复用**：故障后用存活分支证书作「恢复见证」减少重算；但复用前必须过 epoch 屏障并重签租约（**重用即重证**）。

### 2.3 IP-62 RECOVERY-VALIDATOR（恢复验证器 RV）
1. **故障注入矩阵**：crash / timeout / value / correlated × 并发交错 × 人格切换，做 fault fuzzing。
2. **恢复线性一致性检查器**：检出撕裂读、陈旧读、丢失更新、跨 epoch 污染。
3. **恢复风暴压测**：批量故障、租约雪崩、反复 HI/LO 切换下测 MTTR 与安全预算。
4. **MTTR-soundness 曲线与恢复预算标定**：为 C⊥ 保守度、令牌桶速率、q_min 提供实证。

## 4. 实验设计（E95–E102 硬门槛，承接 E87–E94）

| 实验 | 指标 | 门槛 |
|---|---|---|
| E95 恢复 soundness | 恢复期动作越出 C⊥∪已重证集次数；作废证书被使用次数 | 0 起；0 起 |
| E96 恢复 liveness | MTTR p99；重证关键能力数 k；恢复成功率 | < 定义 T_r；≥2；≥99% |
| E97 非污染/恢复线性一致性 | 跨 epoch 污染读；撕裂读；陈旧检查点穿透 | 0；0；0 |
| E98 FTCC 值故障 | 单/双分支故障遮蔽率；值故障检出率；交集误放行 | ≥99%；≥99.9%；0 |
| E99 恢复风暴 | 批量故障下 MTTR 超时率；恢复期安全违例；监控预算丢失 | <5%；0 起；0 |
| E100 回退可行性 | 任意故障态 C⊥ 可达率；C⊥ 自身实机违例 | 100%；0 起 |
| E101 恢复开销 | checkpoint p99 开销；恢复期 p99 决策延迟 | <2ms；<150ms |
| E102 长时程故障并发 | 100h 注入故障下不安全事件；恢复次数；预算透支 | 0 起；≥1000 次；0 |

回退：E100 不达标（C⊥ 不可达）→ 收紧运行域并前置「安全可回退」准入，禁止进入无 C⊥ 保障状态；E95 违例 → 关闭旧证书复用，恢复全程只走 C⊥ 与全量重证；E97 污染 → 恢复串行化 + 强制全量快照；E99 风暴 → 提高恢复门槛、限制并发恢复数；E98 值故障漏检 → 提高 q_min 并降低分支复用。任何红线失败 → 熔断回退 v20。

## 5. 本轮最大风险

**一句话**：整个恢复层的 soundness 都押在「C⊥ 从任意故障态都可达且自身被独立认证」上——若 C⊥ 也由出故障的推理栈计算，或故障发生时系统已处于 C⊥ 不可达的几何/动力学区域，则「恢复」会退化成用一套更精致的说辞包装的停机；因此 E100（回退可行性）与 E95（恢复期 soundness）必须是红线，且 C⊥ 必须由独立静态通道认证，绝不允许循环引用。

# 第 44 轮产物 · 创新点清单 v21：Fail-Recover × Concurrent-Reasoning（CRR × FTCC × RV）× 可验证恢复并发闭环（四层架构 v9）

> 承接第 43 轮产物 v20。本轮**增量插入** IP-60/61/62，并升级既有 IP，不推倒任何层级。核心是把 v20 的「人格 × 并发证书闭环」升级为同时满足 **恢复安全（再认证而非还原）** 与 **并发容错（交集保 sound + 法定人数 + epoch 屏障）** 的可验证闭环。

## 0. 核心 IP 设计

## 2. 关键算法（伪代码）

### IP-60 CRR：回退、屏障、有界恢复与再认证
```
def safe_fallback_guard(x, C_bot):
    # C_bot 独立静态认证，仅依赖最简传感器 + 硬件看门狗
    if not watchdog_ok() or not simple_sensors_ok():
        return HOLD_STOP              # 无独立证据 => 停，不做任何"聪明"推断
    return C_bot.admissible(x)        # 恢复期唯一放行基线

def recovery_barrier(store, e_commit):
    # 只接受 epoch >= 提交点且前后一致的快照
    e1 = store.epoch; snap = store.snapshot; e2 = store.epoch
    if e1 == e2 and e1 >= e_commit:
        return snap
    return None                       # 无干净快照 => 继续在 C_bot 内重试/降级

def recertify(task, snap, C_global, budget):
    if not budget.try_acquire(task.wcet):
        return PENDING                # 风暴：排队，绝不停安全监控预算
    isolate(task.write_set)           # 写集隔离，防污染
    c = evaluate_from(snap, task)     # 只从提交点快照重新评估
    if c.valid and subset(c.admissible, C_global):
        return commit(task, c)        # 签发新证书 + 重签租约
    return C_bot                      # 重证失败 => 回退基线，不重放旧证书

def recover(task, e, store):
    isolate(task.write_set)
    snap = recovery_barrier(store, store.last_commit)
    if snap is None:
        return hold_in(task, C_bot, retry=True)
    C_prime = recertify(task, snap, C_global, recovery_budget)
    return merge_or_hold(task, C_prime)
```

### IP-61 FTCC：冗余分组、交叉校验、交集合成与恢复见证
```
def fault_domains(branches):
    # 按共享依赖分组；同组只贡献一份冗余度，避免伪冗余
    return group_by(branches, key=lambda b: b.dependency_id)

def cross_validate(certs, C_global, q_min):
    trusted = []
    for j, c in certs.items():
        if not c.valid or not subset(c.admissible, C_global):
            continue
        suspect = any(
            not subset(c.admissible, certs[l].admissible)
            for l in certs if l != j and certs[l].valid
        )
        if not suspect:
            trusted.append(j)
    return trusted if len(trusted) >= q_min else []   # 不足法定人数 => 不可认证

def ft_select(branches, certs, C_global, persona, q_min):
    V = cross_validate(certs, C_global, q_min)
    if not V:
        return safe_fallback_guard(current_x, C_bot)
    A_safe = intersect_all(certs[j].admissible for j in V)   # 交集保 sound
    cand = [b for b in branches if subset(certs[b.id].admissible, A_safe & persona)]
    if not cand:
        return negotiate_or_safehold()
    return max(cand, key=score)       # 只取交集内最高分，绝不放行并集

def witness_reuse(survivors, e_commit):
    # 存活分支证书可作恢复见证，但必须先过 epoch 屏障 + 重签租约
    snap = recovery_barrier(survivors.store, e_commit)
    return [c for c in survivors.certs if snap and c.epoch >= e_commit]
```

### IP-62 RV：故障注入与恢复线性一致性检查
```
def fault_scan(schedule, faults):
    for perm in enumerate_interleavings(schedule):
        for f in product(faults, perm):      # crash/timeout/value/correlated × 交错
            trace = simulate_with_fault(perm, f)
            assert no_action_outside(trace, C_bot_union_recertified)
            assert no_revoked_cert_used(trace)
            assert recovery_linearizable(trace, e_commit)   # 无撕裂/陈旧/跨 epoch 污染
    return Invariant()

def recovery_linearizable(trace, e_commit):
    # 存在线性化点，使每次恢复读到"最后提交"或"之后某一致提交"
    for read in trace.recovery_reads:
        if not (read.epoch >= e_commit and read.before_epoch == read.after_epoch):
            return False
    return True
```

### IP-51/57 升级：SafeHold 与最小安全人格
```
def car_guard_with_recovery(e, x, cert_obj, persona, lease, t, mode):
    if mode == RECOVERY:
        return safe_fallback_guard(x, C_bot) and within(car_SafeHold(e), x)
    theta = cert_obj.alpha_e[e] * cert_obj.theta_sim[e]
    m_lookup = cert_lookup_L0(x).m_lo[e]
    m_lease  = lease.m - lease.lam * (t - lease.tau)
    m_cap    = persona_cap[e](persona)
    return min(m_lookup, m_lease, m_cap) >= theta and lease_valid(lease, theta, t)

def persona_on_fault(user, fault, tau_u):
    # 恢复期只允许最小安全人格；信任预算只减不增，绝不还原
    return MinimalSafePersona(user.caps, eps=user.risk_tol), max(0.0, tau_u - c_fault)
```

## 4. 实验设计（E95–E102，硬门槛）

| 实验 | 指标 | 门槛 |
|---|---|---|
| E95 恢复 soundness | 恢复期越出 C⊥∪已重证集；作废证书使用；C⊥ 被绕过 | 0 起；0 起；0 |
| E96 恢复 liveness | MTTR p99；重证关键能力数 k；恢复成功率 | < T_r；≥2；≥99% |
| E97 非污染/线性一致性 | 跨 epoch 污染读；撕裂读；陈旧检查点穿透；丢更新 | 0；0；0；0 |
| E98 FTCC 值故障 | 单/双分支故障遮蔽率；值故障检出率；交集误放行；法定人数正确率 | ≥99%；≥99.9%；0；100% |
| E99 恢复风暴 | MTTR 超时率；恢复期安全违例；监控预算丢失；恢复队列饥饿 | <5%；0 起；0；<1% |
| E100 回退可行性 | 任意故障态 C⊥ 可达率；C⊥ 自身实机违例；C⊥ 独立认证覆盖率 | 100%；0 起；100% |
| E101 恢复开销 | checkpoint p99 开销；恢复期 p99 决策延迟；epoch 屏障重试率 | <2ms；<150ms；<5% |
| E102 长时程故障并发 | 100h 不安全事件；恢复次数；恢复预算透支；相关失效误判 | 0 起；≥1000；0；0 |

回退：E100 不达标 → 前置「安全可回退」准入，禁止进入 C⊥ 不可达状态；E95 违例 → 禁用旧证书复用，全程 C⊥ + 全量重证；E97 污染 → 恢复串行化 + 强制全量快照；E98 漏检 → 提高 q_min、关闭见证复用；E99 风暴 → 限制并发恢复数、提高恢复门槛；任何红线失败 → 全链路熔断回退 v20。

## 5. 风险与缓解（增量）

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| C⊥ 由故障推理栈计算，恢复循环引用自身 | 高 | C⊥ 必须独立静态认证（最简传感器 + 看门狗）；E100 红线；代码路径物理隔离 |
| 故障态下 C⊥ 不可达（已在坏几何/动力学区域） | 高 | 运行域前置「安全可回退」准入；E100 红线；不可回退态禁止进入 |
| 相关失效击穿冗余，多分支一起错 | 高 | 按依赖分组计冗余度；E98/E102 注入相关失效；跨传感器异构冗余 |
| 值故障被交叉校验漏检，交集放行错误动作 | 高 | q_min 法定人数；E98 红线；证书哈希与全局 I 校验；见证复用需重签 |
| 恢复风暴耗尽算力，MTTR 超安全续航 | 中-高 | 令牌桶预算 + 关键级恢复调度 + 监控预算硬隔离；E99 红线 |
| 跨 epoch 单调性不成立，恢复后能力反而虚高 | 中-高 | 恢复只认提交点快照；E97 专测；禁止跨 epoch 复用旧结论 |
| checkpoint 开销拖慢在线路径 | 中 | 增量/双缓冲/异步提交；E101 门槛；按关键级选择 checkpoint 粒度 |
| 恢复算子组合律在写集重叠时失效 | 中 | 写集由工具生成；E97/E99 交错测试；重叠时强制串行 |

## 6. 本轮最大风险

**一句话**：整个恢复层的 soundness 都押在「C⊥ 从任意故障态都可达且自身被独立认证」上——若 C⊥ 也由出故障的推理栈计算，或故障发生时系统已处于 C⊥ 不可达的几何/动力学区域，则「恢复」会退化成用一套更精致的说辞包装的停机；因此 E100（回退可行性）与 E95（恢复期 soundness）必须是红线，且 C⊥ 必须由独立静态通道认证，绝不允许循环引用。
