# 第 13 轮 · POSE-RUBRIC：用「演示位姿尺」量最后 3 厘米，用「官方过程分」选动作，用 72 小时任务卡把验证周期压到 1 天

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。用户本轮提示称“第 1 轮”，但状态文件已是第 12 轮；为保持跨轮编号连续，本文记为第 13 轮。三个词是「快速原型」「位姿估计」「价值对齐」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是补上它们共同缺的三件事：**可测量的任务位姿、可优化的过程分、可快速证伪的任务卡**。

## 0. 先给结论：29.7% 不是模型不够大，而是「最后 3 厘米」没有被测量，也没有被评分

截至 2026-10-31，官网排行榜仍是 8 个模型：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。头尾只差 **9.2pp**。这不是“某个架构领先”，更像是**所有模型共享同一个执行瓶颈**。

但这一轮我要修正第 12 轮的一个判断：瓶颈不只是“最后 3 厘米的闭环”，而是下面三个缺口叠在一起：

1. **状态缺口：没有米制任务状态。** 四路 RGB 能看出“杯子在钩子旁边”，但看不出“夹爪离钩子还有 8mm、还差 7°”。VLA 的语义特征很强，几何状态很弱；SO-101 Bench 的失败分析把这一点总结为“不是指令 grounding，而是几何执行”（arXiv 2610.36420）。没有任务位姿，就没有 near-miss 信号，也无法判断“差一点成功”还是“完全没开始”。
2. **评分缺口：模型在模仿成功轨迹，不在优化官方过程分。** 排名先看 32 任务总平均成功率，再按总平均步骤分。可是训练目标是行为克隆/流匹配，不是“最大化步骤分”。一个动作看起来像演示，不等于它把任务推进到了下一步；VGAS 把这类失败称为“几何歧义下的 near-miss”（arXiv 2602.07399）。
3. **验证缺口：32 任务 × 10 次真机太贵，迭代太慢。** 没有 depth/force/tactile，单任务通道又不计分；如果每个想法都要等一次全量真机，创新循环会被拖死。快速原型不是“随便搭个仿真”，而是把每个任务编译成**可执行、可评分、可泛化、可证伪的 task card**。

所以本轮的押注是 **POSE-RUBRIC**：

> 用演示里的 EE/任务帧位姿构建「相对位姿尺」，把最后 3 厘米变成可测量的进度；用对齐官方过程分的价值头在关键相位选 action chunk；用 PROTO-32 任务卡在 72 小时内决定一个想法该留还是该杀。

一句话：**不要再问“模型能不能看懂任务”，要问“模型知不知道自己离成功还差几毫米、这一步值多少分”。**

三个可验证创新点（不是三个宏大名目）：

1. **POSE-ANCHOR**：从 33k 条成功演示抽关键帧，建「任务帧→夹爪」相对位姿库；在线用同一 VLA 的 SE(3) 位姿辅助头 + 头部双目/腕部 IBVS 估计残差。位姿残差既做 near-miss 检测，也做过程进度。
2. **RUBRIC-V**：在同一 VLA backbone 上加轻量价值头，预测“当前相位/成功率/剩余步骤分”；在接触、对齐、释放等关键相位做 best-of-N chunk 选择，成功即早停，进度回退即恢复。价值头不是第二个模型，而是同一 checkpoint 的辅助头。
3. **PROTO-32**：把 32 个任务写成 task card（物体/受器、初始位姿、success predicate、phase/rubric、demo 子集、位姿库、5 类泛化），用 G1 URDF + Unitree 仿真 + 脚本专家 + 单任务通道做 72 小时快速验证；先证伪，再扩到 32 任务。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **快速原型** | PROTO-32 task card、脚本专家、5 类泛化、sim-real 排序门；一个任务族 72 小时出结论 | 不在仿真里从零训 6B/14B；不追求照片级真实；不把 sim 成功率当官方成功率 |
| **位姿估计** | 演示关键帧位姿库、SE(3) 辅助头、头部双目粗定位、腕部 IBVS 精对齐；位姿残差做进度/near-miss | 不新增独立学习型 6D 物体位姿网络；不假设数据集有物体真值位姿；不假设双目在 1m 外有毫米精度 |
| **价值对齐** | 对齐官方“成功率→步骤分”排序；价值头做 chunk 选择/早停/恢复；人为干扰下对齐人类意图，必要时让位 | 不做通用 RLHF；不训练第二个 VLM 奖励模型；不把“看起来像成功”当成功 |

## 1. 本轮新核实/修正的事实（只列会改变方案的）

### 1.1 榜单是「预览」，不是可复现实测；第 12 轮的 R² 说法要修正

`leaderboard_data.json` 于 **2026-10-08 15:35:03 GMT** 生成，`generated_from = "gen_leaderboard.py"`，包含 8 模型 × 32 任务 = 256 条任务指标。复核结果：

- 32 个详情页的视频全部是“测试视频占位，后续可替换为真实视频文件”，没有真实回放。
- 256 个任务成功率里，**232 个不是 10% 的整数倍**；真实 10 次试验只可能出现 0/10、1/10、…、10/10。
- 每个模型内 `step_score ~ success_rate` 的线性回归 **R² > 0.999999**、最大残差 <0.006；但 8 个模型汇总后的全局 R² 约 **0.9955**，不是第 12 轮写的“全局 R² > 0.999999”。
- 8 个模型的任务成功率两两平均相关系数只有 **0.0975**（min -0.2077，max 0.3527）；任务均值范围 **17.7%（Plug In Ethernet）–30.3%（Stack Cups）**。

**对方案的约束**：榜单可以用来判断“大家都低”“头部路线大概是什么”，但不能用来排任务难度、不能用来估真实失败分布、不能用来证明某个方法有效。真正的 A/B 只能在**单任务测试通道**做。

### 1.2 数据比第 12 轮以为的多了「位姿」，但少了「物体真值」

32 个 HF 数据集合计 **33,276 episodes / 18,282,246 frames / 169.28 h / 30 fps**；32 任务、94 个评分步骤；Easy 12 / Medium 12 / Hard 8；单任务 969–1,533 episodes；平均时长 6.2s（HangCup）–37.6s（ToolboxStorage）。

HangCup 示例的 `meta/info.json` 显示：

- 四路视频 `480×640`；头部双目已校正，基线 **58.2526 mm**，`fx≈282.37`；`state_d435` 是头相机在 base 系的 6D 位姿。
- 状态里有 `left_ee_pose_gripper_base` / `right_ee_pose_gripper_base`，动作里有对应的绝对 EE 位姿；这是位姿库的直接监督。
- 数据字段还包含 `left_ee_pose_gripper_torso` / `right_ee_pose_gripper_torso`（相对躯干）、`state_torso`、`waist_state_joint`、`lower_body`、`action_d435`、`action_torso`、`base_command`、`gripper_controls` 等。
- **修正**：第 12 轮写“腕部相机没有内参”不准确。腕部 **color** 相机在 `camera_params` 里有内参；缺的是到 EE/base 的**外参**。在线用腕部做 IBVS 仍要做手眼标定，但不是“完全无内参”。
- 数据集**没有物体 6D 真值位姿**，也没有 depth/force/tactile。位姿库只能存“任务帧→夹爪”或“演示 EE 轨迹”，不能假装有物体真值。

**对方案的约束**：POSE-ANCHOR 的核心不是“训练一个物体位姿估计器”，而是“用演示 EE/任务帧位姿做相对尺”，再用头部双目和腕部图像补在线观测。

### 1.3 API：`action_chunk_size` 同时是控制参数和吞吐参数

提交模板（2026-10-31 复核）给出：

- 四路 RGB；双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str`；`control_space` 仅 `"joint"` 或 `"ee"`。
- `obs_delta_indices` 决定传哪些键、堆叠几帧；`image_resize` 可缩放；示例 policy 默认 `action_chunk_size = 8`，并给图像 `[-10,-5,-2,0]` 的多帧堆叠。
- `action_chunk_size` 是每次 `get_action` 返回的 leading time-axis 长度；index 0 先执行，其余按顺序执行，直到 evaluator 再次调用；**chunk 内没有新观测，也没有打断机制**。
- 没有 depth、camera_info、force/torque、tactile；token 在 metadata 和每次 `meta.token` 双处校验。
- 评测跨 N 台机器人，提交须从 8765 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态隔离；另有不计分的单任务测试通道。

**关键推论 1（控制）**：如果控制频率 `f=30Hz`、chunk 长度 `H`，则一次调用后开环执行 `H/30` 秒。H=30 是 1 秒，H=8 是 267ms，H=5 是 167ms。最后 3 厘米的接触/插入/释放，必须在 H 较小或关键相位多次调用时才可能闭环。

**关键推论 2（吞吐）**：N 台机器人并行时，总调用频率是 `N·f/H`。如果单模型一次推理 `T_infer` 秒，串行服务能力约 `1/T_infer` 次/秒；要满足 `N·f/H ≤ 1/T_infer`，即：

> **H ≥ N · f · T_infer**

这个不等式比“H 越小越反应”更硬。比如 N=4、f=30、T_infer=180ms，则 H ≥ 21.6，H=24–30 才能用一张 GPU 服务 4 台；想把 H 降到 8，需要约 3 张 GPU 或更快的模型。第 12 轮说“固定 5 步伺服”是不完整的：**H 必须先满足吞吐，再谈反应。**

**关键推论 3（延迟）**：chunk 内最后一个动作的有效观测延迟约 `T_infer + T_net + (H-1)/f`。H 越大，开环越久；H 太小，推理跟不上会停顿。H 是控制参数，不是训练超参。

### 1.4 官方基线：6B/2500h/64 任务，已经把“大模型”这件事做完了

UnifoLM-WLA-1.0 官方 README/训练文档（2026-10-31 复核）：

- **6B** 参数，约 **2,500 h** 真机数据，**64** 个任务，支持二指夹爪 + 多种五指灵巧手。
- 统一 **54D action / 60D state**；默认 `chunk_size=30`、`target_fps=30`、4 步扩散去噪。
- 微调冻结 VLM（`qwen_vl_interface`），只训 DiT action head + robot-state projector；默认单张 **24GB GPU**；支持 LoRA。
- 输出 EE **相对当前 EE** 的 xyz + rotvec；挑战赛 API 要 **base 系绝对 EE** 的 xyz+rpy；adapter 必须把每个未来动作相对**当前观测时刻**的 EE 一次性 compose，再转 rpy。
- WLA 的 54D 包含 dexterous hand / torso / base / legs；挑战赛 `ee` 动作是 2×6 EE + 2×1 gripper + 7 pivot = **21 维**；pivot 的 `pivot_3/4/5` 语义未公开，必须用单任务通道验证。
- 开源时间 2026-09-28；Apache-2.0；数据集合集也标 Apache-2.0。

**对方案的约束**：不要从零训 6B/14B；用 WLA Base 做 action-head/LoRA 微调，把算力投到执行层、位姿头和 value 头。官方 WLA 是否已覆盖 32 任务、pivot 是否一致，是 P0 接口风险。

### 1.5 头部方案的共同瓶颈：语义强、几何弱、恢复弱

- **MolmoAct2**（arXiv 2605.02881）：5B 级，Molmo2-ER + adaptive depth reasoning + flow-matching action expert；官方 blog 称单次 action call 约 **180ms**（base）/ **790ms**（Think），论文在 LIBERO、horizon 10、CUDA Graph 下达到 **55.79Hz** 摊薄控制率。它能“实时”，但排行榜仍只有 29.7%——说明快不等于准。
- **DreamZero**（arXiv 2602.15922）：14B video-diffusion WAM，7Hz 实时闭环；强在物理动态/泛化，弱在接触精度和算力。
- **WALL-OSS-0.5**（arXiv 2605.30877）：4B（3B VLM + action expert），20+ 具身，100 万+ 轨迹/epoch；15 真机任务 60.5% average task progress，比 π0.5 高 17.5%。注意：**progress ≠ success**，最后一步仍会掉。
- **π0.5**（arXiv 2504.16054）：开放世界泛化强，语义子任务 + 低层动作；缺显式米制位姿。
- **GigaBrain-0 / GR00T N1.5**：一个偏世界模型生成数据，一个偏通用人形 VLA 生态；排行榜 22.6% / 20.5%，同样没有解决最后 3 厘米的测量问题。

外部证据：

- **SO-101 Bench**（arXiv 2610.36420，2026-10-27）：4 任务/5 族、138 物体、916 评测 episode、3,629 仿真演示；最好的学习策略约 61%，而“LLM 写代码 + 学习策略抓取”的 harness 达到 83.2%。失败分析指向**几何执行**：抓不准、不熟悉形状的抓法差、恢复弱、空间组合脆。
- **Pose-VLA**（arXiv 2602.19710）：离散 pose token 做通用 3D 预训练，再对齐到机器人动作；RoboTwin 2.0 79.5%、LIBERO 96.0%、真机 100 演示。说明“位姿作为中间表示”有据可依。
- **OASIS**（arXiv 2605.25829）：用 SE(3) EE 轨迹预测对齐观测空间和动作空间，动作 decoder 在 pose-supervised hidden states 上生成 chunk；在仿真/真机的成功率和 OOD 上优于 VLA/WAM。说明“位姿辅助头”不必是第二个模型。注意：OASIS 用 metric depth；挑战赛没有 depth，我们只能用头部双目/pose head 替代，精度和鲁棒性要打折。
- **VGAS**（arXiv 2602.07399）：微调 VLA 做高召回 proposal，Q-Chunk-Former 做几何 grounded critic，inference-time best-of-N 选 chunk；在少演示/分布漂移下提升。说明“生成-选择”是可行路线，但独立 critic 有单模型合规风险。
- **Retrieve-then-Steer**（arXiv 2605.10094）：在线成功记忆、progress-calibrated 成功片段、confidence-adaptive 注入 flow-matching sampler；冻结 VLA 也能提升闭环可靠性。说明“成功经验检索”可作为 value/pose 的补充。
- **RoboReward**（arXiv 2601.00675）与 **RARM**（arXiv 2606.22027）：VLM/对比式奖励模型能做 dense progress，但没有任何模型跨任务全能；RARM 用单条成功演示 + confidence gate，在 9 仿真 + 4 真机上最好。说明“价值头”要小而校准，不能盲信大 VLM。
- **Capability-Aware Arbitration**（arXiv 2609.25369）：VLM 意图置信度 + VLA 能力置信度（动作轨迹离散度/局部不稳定）做共享控制；12 人实验 92% vs 手动 83%、仅意图 44%、固定混合 10%。说明人为干扰下“让位”不能只看意图，还要看 VLA 自己行不行。
- **RGBTrack**（arXiv 2506.17119）：RGB-only 6D pose tracking，FoundationPose 架构 + 二分搜索 + render-and-compare + XMem/Kalman，实时。说明无 depth 也能做位姿，但它是学习/渲染模型，在线作为第二模型有合规风险；我们只用它做离线对照/教师。
- **Sim-to-Real Pipeline**（arXiv 2609.21817）：仿真专家轨迹在 Franka FR3 上开环回放，采集配对真机数据，直接量 sim-real gap。说明 PROTO-32 的“脚本专家 + 配对回放”有现成范式。

### 1.6 为什么是现在：官方基座 + 33k 演示 + 单任务通道 + 位姿字段

- WLA 6B Base + 微调代码已开源，24GB 可跑；不必从零训。
- 33k 演示里有 EE 位姿、头部相机位姿、夹爪开合、四路视频；足够做关键帧和位姿库。
- 单任务通道不计分，但能快速 A/B；这是“快速原型”的真实反馈口。
- 头部模型仍低于 30%，且榜单是预览；现在做“执行层/评分层”比再做一个大模型更有边际收益。

## 2. 诊断：三个缺口，不是三个模型

### 2.1 状态缺口：语义特征不等于米制状态

VLA 的 VLM backbone 擅长“这是什么/要做什么”，不擅长“夹爪离孔还有几毫米”。Pose-VLA 的摘要直接说：VQA 优化的 VLM 会忽略决定动作模式的细微 3D 状态变化。OASIS 进一步说：观测空间的中间特征和动作空间的刚体几何不一致，动作 decoder 只能隐式恢复几何。

**推论**：加一个显式的 SE(3) 中间表示/位姿辅助头，比加更多语义 token 更对症。位姿头可以是同一 backbone 上的小 head，不需要第二个模型。

### 2.2 评分缺口：行为克隆在优化“像不像”，不是“得几分”

官方排名先成功率、再平均步骤分。一个 chunk 可能“看起来像演示”，但把杯子推过了 2mm，导致挂不上；也可能“动作很丑”，但把杯子挂上了。BC/流匹配的似然目标不区分这两种。

VGAS 的 near-miss 现象、RoboReward 的“没有模型跨任务全能”、RARM 的“视觉上合理但物理错误的状态会被高奖”都说明：**需要的是校准过的过程价值，不是更大的生成模型。**

**推论**：价值头要预测“当前相位 + 成功率 + 剩余步骤分”，并且在关键相位做**选择**，而不是全时段 best-of-N。全时段 best-of-N 会把延迟乘 N，吞吐直接崩。

### 2.3 验证缺口：没有 task card，就没有快速证伪

32 任务 × 10 次真机 = 320 trials；每次最多 180s。全量一次就是巨大的工程/时间成本。单任务通道不计分，但如果 task card 不明确（success predicate、phase、variants、demo 子集），A/B 也不可信。

**推论**：PROTO-32 的产物不是“一个仿真器”，而是**可执行的 task card + 脚本专家 + 指标 + sim-real 排序门**。如果一个想法在 3 个任务上不能过门，就不配进入 32 任务全量。

### 2.4 为什么不是“再加一个模型”

官方规则要求所有任务基于**同一模型**，不得混合多个模型一起测试。因此：

- 同一 checkpoint 的 action head + pose head + value head：合规，推荐。
- 同一 VLA + 确定性几何控制器/IBVS：合规，控制器不是学习模型。
- 独立 6D pose 网络 / 独立 VLM reward / 第二个策略：高风险，可能被判混合模型；最多做离线教师/对照，不进在线提交。

## 3. 方法：POSE-RUBRIC

### 3.1 总架构

```text
                         ┌──────────────────────────────┐
```

### 3.2 POSE-ANCHOR：演示位姿尺

#### 3.2.1 关键帧

每条成功演示按夹爪开合、EE 速度极小值、接触前后，切 3–6 个相位：

```text
approach → pre_grasp → grasp → lift/transport → pre_place → place → release
```

每个关键帧存：

```text
task_id, episode_id, phase, t,
T_base_to_gripper (4×4),
T_head_to_gripper (4×4),
T_task_to_gripper (4×4),   # 任务帧由 CAD/标注/首帧定义
gripper_width,
T_base_to_task (4×4),      # 每任务一次标注
success
```

这里不存“物体真值位姿”，因为没有。`T_task_to_gripper` 是相对任务帧（钩子、插座、拉链、碗沿、瓶盖）的夹爪位姿；任务帧在仿真/真机初始帧用 CAD/手工 3D 点/平面拟合定义一次。

#### 3.2.2 相对位姿残差

目标位姿 `T* = T_task_to_gripper^demo`，当前位姿 `T = T_task_to_gripper^now`：

```text
e = Log( T*⁻¹ · T ) ∈ se(3)
r_pose = || e ||_W = sqrt( eᵀ W e )
```

- `r_pose` 小：夹爪在正确相对位姿附近。
- `r_pose` 在某方向大：near-miss 的方向（例如 z 差 4mm、yaw 差 6°）。
- `r_pose` 突然变大：人移动了物体/夹爪滑移/任务帧错。

位姿进度：

```text
p_pose = exp( - r_pose / σ_phase )
```

`σ_phase` 按相位设：approach 5cm，pre_grasp 1cm，contact 5mm，insert 2mm。不要用一个全局 σ。

#### 3.2.3 在线位姿

三条路，按精度/成本排序：

1. **头部双目粗定位**：已校正，基线 58.2526mm，`Z = f·b/d`。在 1m 处，1px 视差约 6.1cm；在 0.5m 处约 1.5cm；在 0.3m 处约 0.55cm。所以双目只做“粗”，不做最后插入。
2. **Pose head**：同一 VLA 的 SE(3) waypoint 预测；不需要物体 CAD，不需要第二模型；精度目标 1–2cm，做粗对齐和进度。
3. **腕部 IBVS**：腕部有内参、无外参；用手眼标定或 image-space 目标做最后 3cm。1px 在 0.1m 处约 0.35mm、0.3m 处约 1.06mm；比头部双目在 1m 处高一个数量级。

回退：如果位姿头/双目都不可信，直接回退到 Base VLA + 腕部模板/边缘 IBVS；不要让位姿模块阻塞动作。

#### 3.2.4 为什么不是“独立 6D pose 网络”

- 独立网络是第二个学习模型，单模型合规风险。
- 数据集没有物体 6D 真值，训练独立物体位姿器只能靠合成/自监督，sim-real gap 大。
- 任务帧相对位姿 + 同一 backbone 的 pose head 已经够做 near-miss；最后精度靠 IBVS，不靠物体位姿分类。

RGBTrack 这类 RGB-only 6D pose 可以作为**离线教师/对照**，不进在线提交。

### 3.3 RUBRIC-V：对齐官方过程分

#### 3.3.1 过程分代理

官方只公开“平均步骤分”，没有逐任务 100 分细则。我们不能假装知道官方每一步的分数；我们用 task card 的 phase 进度做**代理**，并在单任务通道校准：

```text
p_t = (phase_index + subphase_progress) / K
s_t = P(success | h_t)
v_t = expected remaining step score
```

- 训练标签：成功演示的 phase 标签单调递增；终局成功 `s=1`；失败/截断为 `s=0`；near-miss 用位姿残差和终局结果做弱标签。
- 价值头输入：`h_t` + proprio + phase embedding + pose residual。
- 输出：`p_t, s_t, v_t`；小 MLP，几百万参数，和 action head 同 checkpoint。

#### 3.3.2 chunk 评分

对候选 chunk `τ_i`（i=1..N）：

```text
S(τ_i) = w_s·s_i + w_p·p_i + w_g·exp(-r_pose_i/σ) + w_j·(-jerk_i) + w_c·consistency_i
```

`τ* = argmax_i S(τ_i)`。

- `s_i`：价值头对 chunk 末状态的成功率。
- `p_i`：过程进度。
- `r_pose_i`：pose head/位姿库给出的末端相对残差。
- `jerk_i`：动作平滑/安全惩罚。
- `consistency_i`：与 Base VLA 原 chunk 的偏差，防止价值头把动作带偏。

只在**关键相位**做 best-of-N：pre_contact、align、insert、release。approach/transport 用 N=1，避免延迟乘 N。

#### 3.3.3 早停与恢复

- **早停**：`s_t > τ_s` 且 success predicate 成立（例如杯子挂住 2s、插头到位、拉链闭合）→ 停止，不再输出“多推一下”的 chunk。这能减少“成功后又碰倒”的失败。
- **恢复**：`p_t` 连续 2 个 chunk 下降，或 `r_pose` 卡住 >1s → 后退 2–3cm、重观测、重规划；最多 2 次，然后放弃当前子目标。
- **人为干扰**：检测到人手进入/物体被移动 → 让位/等待；人离开且场景稳定 1s → 重定位、重规划。

#### 3.3.4 不是通用 RLHF

这里的“价值对齐”是**任务评分对齐 + 人类意图对齐**，不是训练一个通用偏好模型：

- 评分对齐：让推理时选择最大化官方排序（成功率→步骤分）。
- 人类对齐：在“人为干扰”泛化项下，知道何时让位、何时继续。
- 不训练第二个 VLM 奖励；价值头是同 backbone 的小头；不可信时回退确定性位姿/规则。

#### 3.4.2 场景与专家

- G1 URDF + Dex1 + 桌子 + 物体；优先用 `unitree_sim_isaaclab` / `unitree_mujoco`；资产缺失时用简化几何代理，不追求照片级。
- 脚本专家：回放成功演示的 EE 轨迹 + IK；对位置/干扰物变体做重定向；对未见物体用基元（抓取点 + 抬升 + 放置）。
- 5 类泛化：位置随机、干扰物、背景纹理、未见物体、脚本人手/遥操作干扰。
- 指标：成功率、phase 进度、位姿残差、接触时间、恢复次数、单次耗时。

#### 3.4.3 72 小时节奏

| 时间 | 交付 | 过门条件 |
|---|---|---|
| 0–24h | 3 个任务的 task card（HangCup、Plug Ethernet、Stack Cups）+ 回放 + 指标 | 能重复跑 20 trials，success predicate 无歧义 |
| 24–48h | 5 类变体 + 脚本专家 + Base WLA 基线 | 每个变体至少 10 trials；失败可分类 |
| 48–72h | sim vs 单任务通道 A/B（3 任务） | Spearman >0.6 才把 sim 当排序工具；否则只当单元测试 |

如果 72h 内不能过门，杀掉这个想法，不进入 32 任务全量。这是“快速原型”的真正含义：**用最小证据决定留/杀**。

### 3.5 CHUNK-SERVO 更新：H 由吞吐和延迟共同决定

第 12 轮说“30 步规划 + 5 步伺服”。本轮修正为：

```text
H ≥ N·f·T_infer              # 吞吐约束：不排队/不停顿
T_eff ≈ T_infer + T_net + (H-1)/f   # 有效观测延迟
```

- N=1、f=30、T_infer=180ms → H≥5.4，H=6–8。
- N=4、f=30、T_infer=180ms → H≥21.6，H=24–30；想 H=8，需要约 3 张 GPU。
- T_infer=790ms（MolmoAct2-Think）→ N=1 需要 H≥24；N=4 需要 H≥95，不现实；Think 不适合多机器人并行。
- 如果 H 太小导致 `H/f < T_infer + T_net`，机器人会在 chunk 之间停顿；这比开环更糟。

**执行策略**：

- 默认 H=8（示例 policy 的默认值），但必须实测 T_infer/T_net/N 后再定。
- 单 GPU、N=4 时用 H=24–30，接受 1 秒开环；把闭环希望放到关键相位的多次调用/恢复，而不是假装 30Hz 伺服。
- 有多 GPU 时，H=8–12，关键相位 best-of-N；用吞吐换反应。
- 不要在没有实测的情况下宣称“5 步闭环 30Hz”。

### 3.6 人为干扰：价值对齐的另一半

人为干扰是 5 类泛化之一，每个任务 2 次。策略：

1. **检测**：同一 VLA backbone 的 VLM 头/动作分散度 + 画面运动/遮挡 + 物体位姿突变；不引入第二个策略模型。
2. **意图**：取走/移动/调整/观察；高意图置信度 + 低 VLA 能力置信度 → 让位。
3. **仲裁**：`α = sigmoid(a·intent_conf + b·(1-capability_conf) + c)`；α 高则机器人降权/停止；人离开且稳定 1s 后恢复。
4. **恢复**：重新定位任务帧/物体，更新位姿库目标；不要假设物体还在原位。
5. **评分**：人为干扰下“不碰撞、不抢、能恢复”本身是步骤分；宁可让位，不要硬抢。

Capability-Aware Arbitration 的 92% vs 44% 说明：只看人类意图、不看 VLA 能力，会“过度帮忙”；我们的 α 要把两边都放进去。

## 4. 竞赛策略：320 trials 是投资组合

### 4.1 算术

- 32 任务 ×10 次 = 320 trials；每次最多 180s；总真机时间上限约 16h（不含 reset/换物体）。
- 排名先总平均成功率，再总平均步骤分，再提交时间。
- 单任务通道不计分，但能做 A/B；正式提交机会有限（手册未给次数，按保守假设）。

### 4.2 任务组合（先验，待单任务通道更新）

先做 4 个“方法验证任务”，再做 28 个“泛化任务”：

| 用途 | 任务 | 理由 |
|---|---|---|
| 快速闭环 | Hang the Cup (6.2s)、Stack Cups (19.8s) | 短、接触明确、位姿尺好定义 |
| 插入/对齐 | Plug Ethernet (16.4s)、Plug Charger (15.1s) | 最后 3cm 的典型，步骤分明显 |
| 长程/恢复 | Toolbox Storage (37.6s)、Zip Up (14.1s) | 多阶段、易掉步、考恢复 |

**不要**按榜单任务均值排难度：榜单是预览，任务均值 17.7–30.3 的差异没有实测意义。

| 门 | 假设 | 指标 | 杀掉条件 |
|---|---|---|---|

## 7. 风险与合规

- **单模型**：只提交一个 checkpoint；pose/value 是同 backbone 辅助头；IBVS/规则是确定性控制器；不加载第二个策略/VLM 奖励。
- **官方评分未知**：value 头用 phase 代理，必须在单任务通道校准；不宣称“官方步骤分”。
- **位姿无真值**：任务帧靠标注/CAD/首帧；未见物体回退 VLA/IBVS；不假装有物体 6D 真值。
- **双目精度**：1m 处 1px≈6cm，不能做最后插入；最后 3cm 必须腕部/pose head。
- **吞吐**：N=4、H=8、6B 单卡不现实；用 `H ≥ N·f·T_infer` 先算，必要时加 GPU/换小模型/加长 chunk。
- **延迟**：Think/14B 模型不适合多机器人并行；base 5B 也要实测。
- **数据许可**：WLA 和数据集标 Apache-2.0；仍要保留 NOTICE/第三方许可。
- **人为干扰**：宁可让位，不要硬抢；恢复要重定位，不假设物体没动。
- **榜单**：预览数据，不能当实测；正式结论只来自单任务通道/全量提交。

## 8. 一句话押注

**本轮最值得押注的是 POSE-RUBRIC：用同一 VLA 的 SE(3) 位姿头/演示位姿库把“最后 3 厘米”变成可测量的进度，用对齐官方过程分的价值头在关键相位选 chunk，再用 PROTO-32 在 72 小时内验证——不新增第二个学习模型。**

## 0. 结论与边界

### 0.1 一句话结论

**榜首不到 30%，不是因为没人能训更大的 VLA，而是因为「最后 3 厘米」没有被米制测量，也没有按官方过程分被选择。** 本轮把问题拆成三个可执行部件：POSE-ANCHOR（位姿尺）、RUBRIC-V（过程分价值头）、PROTO-32（72 小时任务卡）。三者都不新增第二个学习模型：pose/value 是同一 VLA backbone 的辅助头，IBVS/规则是确定性控制器。

### 0.2 证据等级

| 等级 | 含义 | 本轮用途 |
|---|---|---|
| A | 官网/官方仓库/官方数据直接核对 | 规则、API、数据字段、WLA 参数、榜单 JSON |
| B | 论文摘要/模型卡/第三方评测 | 头部模型路线、相关工作、SO-101 Bench 结论 |
| C | 我们的推断/设计 | 三个缺口、POSE-RUBRIC 架构、实验门、预算 |

### 0.3 本轮不做什么

- 不从零训 6B/14B VLA 或 world model；官方 WLA Base 已开源。
- 不做独立学习型 6D 物体位姿网络在线运行；单模型合规风险 + 无物体真值。
- 不做逐任务策略/逐任务 LoRA；通才单模型。
- 不做 30Hz 广域网伺服；先算 `H ≥ N·f·T_infer`。
- 不把预览榜单的任务均值当真实难度；正式结论只来自单任务通道/全量提交。
- 不做力/触觉闭环；API 没有。

## 2. 问题形式化

### 2.1 评分

官方排序：

```text
maximize  S_total = (1/32) Σ_t success_rate_t
subject to tie-break: (1/32) Σ_t step_score_t, then earlier submission
```

单任务 10 次，5 类泛化各 2 次。我们不知道每次的 step score 函数，只知道它存在且用于 tie-break。

**推论**：优化目标不是“像演示”，而是“成功 + 过程分”。当成功不确定时，选择能保留更多过程分的动作；当成功确定时，早停。

### 2.2 接口时间/吞吐

设控制频率 `f`、chunk 长度 `H`、单次推理 `T_infer`、网络 `T_net`：

```text
开环时长           T_open = H / f
单机器人调用频率   c = f / H
N 机器人总频率     C = N · f / H
单模型串行能力     C_model = 1 / T_infer
吞吐可行条件       H ≥ N · f · T_infer
最后一个动作延迟   T_eff ≈ T_infer + T_net + (H-1)/f
```

**注意**：`T_eff` 是“chunk 内最后一个动作所依赖的观测已经过了多久”；不是端到端 RTT。`T_infer` 是模型前向；如果服务端排队，还要加排队时间。

#### 数值表（假设 f=30Hz、T_net≈0）

|---:|---:|---:|---:|---|
| 1 | 8 | 3.75 | 够 | T_eff≈180+233=413ms |
| 2 | 8 | 7.50 | 不够 | 需 H≥12 或 2 卡 |
| 4 | 8 | 15.0 | 不够 | 需 H≥24（1 卡）或 ~3 卡 |

| 4 | 12 | 10.0 | 不够（1 卡） | 2 卡可；T_eff≈547ms |
| 4 | 8 | 15.0 | 3 卡可 | T_eff≈413ms |

**结论**：第 12 轮的“固定 5 步伺服”在 N=4、6B、单卡下不成立。H 必须先满足吞吐；要短 chunk，就加 GPU/换小模型/减少 N。不要在没有 N/T_infer 实测时写死 H。

### 2.3 位姿状态

任务帧 `F`（钩子/插座/拉链/碗沿/瓶盖），夹爪 `G`：

```text
T_{G←F}(t) = T_{B←G}(t)^{-1} · T_{B←F}(t)
```

演示目标 `T* = T_{G←F}^{demo}`；残差：

```text
e = Log( T*⁻¹ · T_{G←F}^{now} ) ∈ se(3)
r_pose = ||e||_W
```

`r_pose` 是 near-miss/进度/恢复的统一信号。它不需要物体真值，只需要任务帧和夹爪位姿；任务帧用 CAD/手工关键点/平面拟合定义。

### 2.4 价值/进度

```text
p_t = P(phase progress | h_t) ∈ [0,1]
s_t = P(success | h_t) ∈ [0,1]
v_t = E[remaining step score | h_t]
```

训练标签来自 task card 的 phase 和终局成功；`v_t` 是代理，不是官方分。单任务通道用来校准 `v_t` 与官方 step score 的单调关系。

### 2.5 可辨识性

- 位姿：头部双目在 1m 处 1px≈6cm，不能辨识毫米级；腕部 IBVS 在 0.1m 处 1px≈0.35mm，能辨识最后 3cm。多尺度是必须的。
- 价值：如果 phase 标签错了，价值头会学错；task card 的 success predicate 必须可执行、可观察。
- 单模型：辅助头必须共享 backbone/checkpoint；独立模型不可控。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
┌────────────────────────────────────────────────────────────┐
│ GPU 0: SharedBackbone (WLA 6B + pose/value heads)          │
│   ├── InferenceWorker: queue / optional dynamic batch      │
│   ├── PortPolicy(port 8765) ── PolicyService thread        │
│   ├── PortPolicy(port 8766) ── PolicyService thread        │
│   ├── ...                                                  │
│   └── PortPolicy(port 8765+N-1)                            │
└────────────────────────────────────────────────────────────┘
```

- 每个端口一个 `PortPolicy`，持有独立的状态机/位姿库缓存；`reset()` 只清该端口。
- 一个 `SharedBackbone` 共享权重；GPU worker 串行或动态 batch。
- N 大时，多 GPU 复制**同一权重**，按端口分片；不是多个不同模型。
- **不要**在一个 GPU 上加载 N 份 6B 权重；会 OOM。
- 如果 N=4、H=8、T_infer=180ms，单卡吞吐不够；按 2.2 加卡或加长 H。

### 3.3 `get_action` 伪代码

```python
def get_action(self, obs):
    state = self.parse(obs)                    # images, joints, EE, gripper, language
    self.fsm.update(state)

    if self.fsm.human_intervening(state):
        return self.yield_chunk(state)          # zero/slow, keep token/shape

    if self.fsm.should_reobserve(state):
        return self.servo_chunk(state)          # deterministic small correction

    h = self.backbone.encode(state)             # shared hidden
    pose = self.pose_head(h)                    # SE(3) waypoint / residual
    value = self.value_head(h, state)           # p, s, v

    if self.fsm.phase in CRITICAL_PHASES:
        cands = [self.action_head(h, noise=i) for i in range(N_BEST)]
        scores = [self.rubric_score(c, pose, value, state) for c in cands]
        chunk = cands[argmax(scores)]
    else:
        chunk = self.action_head(h)             # N=1

    chunk = self.adapt_54d_to_21d(chunk, state) # compose EE, pivot, gripper
    chunk = self.safety_clip(chunk, state)
    return self.pack(chunk, self.token)         # shapes (H, ...), meta.token
```

`rubric_score`：

```python
def rubric_score(cand, pose, value, state):
    r = pose_residual(cand, pose, state.pose_bank_target)
    return (w_s * value.success
            + w_p * value.progress
            + w_g * exp(-r / sigma_phase)
            - w_j * jerk(cand)
            - w_c * deviation(cand, state.base_chunk))
```

### 3.4 WLA 54D → 挑战赛 21D adapter

#### EE

WLA 输出相对**当前观测时刻** EE 的 `Δξ = (Δxyz, Δrotvec)`。挑战赛要 base 系绝对 `xyz+rpy`。

```python
for k in range(H):
    dT = exp_se3(cand[k].left_ee_delta)      # 4×4，相对当前观测时刻 EE
    T_abs_k = state.T_base_ee @ dT           # 每个未来动作都相对当前 t，不是相对上一步
    left_ee[k] = xyz_rpy(T_abs_k)
```

- 官方文档明确：未来动作是相对**当前** EE，不是相对 chunk 上一步；不要逐步累乘，否则会漂移。
- 左右臂分别 compose。
- 如果 WLA 输出 30 步、挑战赛 H=8：优先截断前 8 步（0–233ms），不要重采样改变动力学；或在微调时直接训练 H=8。截断/重采样的增益必须用单任务通道验证。
- rotvec → 旋转矩阵 → 旋转矩阵 → rpy；确认挑战赛 rpy 约定（外旋/内旋）与 `example_env` 一致。
- gripper 直通/裁剪到合法范围；WLA raw 与挑战赛 raw 是否同尺度要实测。

#### pivot

挑战赛 `pivot = [vx, vy, angle_z, ?, ?, ?, height]`；WLA 有 base `vx, vy, omega_z`、height、waist/torso/legs。

- 先映射 `vx, vy, angle_z, height`；`pivot_3/4/5` 置 0 或按单任务通道实测。
- 不要把 WLA 的腰/腿动作硬塞进 pivot；先保守。
- 如果控制空间选 `joint`，则完全绕过 EE compose，但要用 WLA 的关节输出；WLA 当前是 EE 相对，joint 路线需要额外 IK/映射，风险更高。**默认 `ee`。**

#### 频率/尺度

- WLA `target_fps=30`；挑战赛数据 30fps；若评测频率不同，动作需要重采样/时间缩放。
- 夹爪/EE 单位：米/弧度；dataset 是米；确认挑战赛 API 也是米/弧度（`example_env` 会校验）。

### 3.5 状态机

```text
INIT
  → APPROACH        # N=1, 位姿粗对齐
  → PRE_GRASP       # N=1/2, 腕部 IBVS
  → GRASP           # N=2, 夹爪闭合 + 位姿残差
  → LIFT/TRANSPORT  # N=1, 进度监控
  → ALIGN           # N=2–4, 关键相位
  → CONTACT/INSERT  # N=2–4, 小步 + 力代理（电流/速度）
  → VERIFY          # success predicate
      ├─ success → DONE（早停）
      ├─ near-miss → RECOVER（后退 2–3cm，重试 ≤2）
      └─ fail → REPLAN
  → HUMAN           # 检测到干扰 → 让位/等待 → 重定位 → 恢复
```

- `CRITICAL_PHASES = {PRE_GRASP, GRASP, ALIGN, CONTACT, RELEASE}`。
- 每个相位有 `sigma_phase` 和 success predicate；不要用全局阈值。
- `RECOVER` 最多 2 次；超过则放弃当前子目标，避免 180s 超时。

### 3.6 单模型合规

| 模式 | 描述 | 合规 | 备注 |
|---|---|---|---|
| C1 | 同一 checkpoint + action/pose/value 辅助头 | 推荐 | 一次 forward 出多个头；权重同文件 |
| C2 | 同一 VLA + 确定性 IBVS/规则 | 推荐 | 控制器不是学习模型 |
| C3 | 同一 VLA + 独立学习型 6D pose 网络 | 高风险 | 可能被判混合模型 |
| C4 | 同一 VLA + 独立 VLM reward | 高风险 | 同上 |
| C5 | 多策略路由/逐任务模型 | 禁止 | 违反单模型 |

**提交策略**：C1+C2；C3/C4 只做离线教师/对照。若官方对“辅助头”有疑问，保留“仅 action head”的回退开关。

## 4. POSE-ANCHOR

### 4.1 离线管线

```text
HF LeRobot episodes
  → parse meta/info.json
  → extract EE poses / gripper / head pose / videos
  → detect keyframes (gripper events, EE velocity minima)
  → annotate task frame F (CAD/manual 3D points/plane)
  → compute T_{G←F} at keyframes
  → write pose_bank/{task}.parquet
```

- 只处理成功 episodes；失败/near-miss 单独存，做 value 负样本。
- 每个任务 3–6 个 phase；每 phase 保留多个模式（左/右臂、不同初始位姿）。
- 任务帧 `F` 每任务定义一次；如果物体可变（杯子/碗），用类别级任务帧（钩子/碗沿/插座），不要用实例 CAD。

### 4.2 关键帧检测

| 信号 | 用途 |
|---|---|
| 夹爪开合事件 | grasp/release 边界 |
| EE 线速度/角速度局部极小 | pre_grasp/pre_place |
| EE 到任务帧距离 | approach/align/contact |
| 夹爪宽度变化 | 抓取成功/滑移 |
| 视频运动/遮挡 | 人为干扰/失败 |
| 终局 success predicate | DONE/失败 |

没有力/触觉，不能用接触力；用 EE 速度、夹爪宽度、位姿残差、电流（如果 API 不给就放弃）做代理。

### 4.3 位姿库 schema

```text
pose_bank/T01.parquet
columns:
  task_id: string
  episode_id: int
  phase: string
  t: float
  T_base_gripper: float[16]     # 4×4 row-major
  T_head_gripper: float[16]
  T_task_gripper: float[16]     # 任务帧→夹爪
  T_base_task: float[16]        # 每任务一次
  gripper_width: float
  success: bool
  near_miss: bool
```

- 不存物体 6D 位姿；没有真值。
- 如果后续标注了物体位姿，另开列，不混进主 schema。
- 每个任务一个 Parquet；按 phase/初始位姿建索引；文件小，加载快。

### 4.4 检索

```text
candidate = filter(task_id, phase, arm)
score = w1·||T_base_gripper_init - T_base_gripper_init^demo||
      + w2·DTW(EE_traj_now, EE_traj_demo)
      + w3·image_similarity(initial_frame)
target = weighted median of top-k T_task_gripper
```

- 初始位姿/语言/任务 id 先过滤；DTW 只用最近 1–2s 的 EE 轨迹。
- 图像相似度用简单颜色/边缘/特征，不引入第二个学习模型；或者只用位姿。
- 返回 top-k 的中位数，降低单条演示噪声。
- 检索失败 → 回退 Base VLA，不阻塞。

### 4.5 在线位姿

#### 头部双目

- 已校正；用 SGBM/块匹配（确定性）算视差，`Z = f·b/d`，`f≈282.37`，`b=0.0582526m`。
- 误差：`dZ ≈ Z²/(f·b)·dd`；1px 视差误差：
  - 1.0m：≈6.1cm
  - 0.5m：≈1.5cm
  - 0.3m：≈0.55cm
  - 0.1m：≈0.06cm（但近处遮挡/纹理差）
- 用途：approach/粗定位；不做最后插入。

#### Pose head

- 输入：`h_t` + proprio + 任务帧 token；输出未来 `K` 个 SE(3) waypoint（camera/base 系）或相对任务帧位姿。
- 监督：演示 EE 位姿（base 系）；坐标系转换到 camera/任务帧。
- 输出头：6D rotation + 3D translation；或 9D matrix + Gram-Schmidt。
- 损失：`L = ||t - t*||_1 + λ·||R - R*||_F + λ_v·||Δ - Δ*||`。
- 只在有 pose 标签的帧训练；无标签帧 mask。
- 目标精度 1–2cm；不追求毫米。

#### 腕部 IBVS

- 腕部有内参、无外参；用 image-space 目标（把手/边缘/孔）做 IBVS。
- 目标可由演示关键帧的腕部图像块/模板给出；在线用模板匹配/边缘/光流。
- 误差 `e_img = (u - u*, v - v*)`；控制 `Δx = -λ J⁺ e_img`，只在小步/接触段。
- 1px 在 0.1m 处约 0.35mm（横向）；适合最后 3cm。
- 没有 depth 也能做 IBVS；深度用运动/已知任务帧/pose head 补。

### 4.6 多尺度误差预算

| 阶段 | 典型距离 | 可用观测 | 目标精度 | 方法 |
|---|---:|---|---:|---|
| approach | 0.5–1.0m | 头部双目 | 2–5cm | 双目/pose head |
| pre_grasp | 0.2–0.5m | 双目 + 腕部 | 1–2cm | pose head + 腕部 |
| grasp | 0.05–0.2m | 腕部 | 5–10mm | 腕部 IBVS/位姿残差 |
| contact/insert | 0–5cm | 腕部 | 2–5mm | 腕部 IBVS + 小步 |
| release | 0–5cm | 腕部 | 5mm | 位姿 + success predicate |

**结论**：没有单一观测能覆盖全尺度；POSE-ANCHOR 必须是“双目粗 + pose head 中 + 腕部精 + 规则兜底”。

### 4.7 回退

- 位姿库检索失败 → Base VLA。
- pose head 置信度低/残差跳变 → 腕部模板 IBVS。
- 双目纹理差/遮挡 → 腕部/运动。
- 人为干扰 → 让位/重定位。
- 任何回退都不能破坏 action shape/token。

## 5. RUBRIC-V

### 5.1 过程分代理

官方只公开“平均步骤分”，没有逐任务细则。我们用 task card 的 phase 进度做代理：

```text
p_t = (k + α_t) / K
```

- `k`：当前 phase 索引；`α_t ∈ [0,1]`：phase 内进度（由位姿残差/子目标距离估计）。
- `s_t`：终局成功率；`v_t`：剩余步骤分代理。
- 在单任务通道记录官方 step score，拟合 `step_score ≈ g(p_final)`；如果单调，代理有效；否则只用 `p_t` 做排序，不宣称分数。

### 5.2 标签

| 标签 | 来源 | 注意 |
|---|---|---|
| phase | task card + 关键帧 | 3–6 phase/任务；人工抽检 |
| `p_t` | phase 索引 + 子目标距离 | 单调；失败/near-miss 也要标 |
| `s_t` | episode 终局成功 | 成功=1；失败=0；截断=0 |
| near-miss | 位姿残差小但终局失败 | 关键负样本 |
| human | 人为干扰片段 | 让位/恢复标签 |
| step_score | 单任务通道官方反馈 | 只用于校准，不训练大模型 |

### 5.3 价值头

```text
input:  h_t (D) + proprio (43) + phase_emb (16) + pose_residual (6)
hidden: 2–3 层 MLP, 512–1024
output: p_t, s_t, v_t
params: ~1–5M
```

- 与 action head 同 checkpoint；可冻结 backbone 只训头，或联合 LoRA。
- 损失：

```text
L = L_p(p, p*) + λ_s·BCE(s, s*) + λ_v·L_v(v, v*) + λ_r·RankingLoss
```

- Ranking：同一任务/相位，成功 chunk 应高于 near-miss/failed chunk；margin loss。
- 校准：temperature scaling / isotonic；输出 ECE。
- 不确定性：MC dropout 或 ensemble of heads（同 checkpoint 多个头，不是多个模型）；高不确定 → 回退 N=1/规则。

### 5.4 chunk 评分

```text
S(τ_i) = w_s·s_i + w_p·p_i + w_g·exp(-r_pose_i/σ_phase)
       - w_j·jerk_i - w_c·||τ_i - τ_base||²
```

- `τ_base`：Base VLA 的原 chunk；`w_c` 防止价值头把动作带偏。
- `jerk_i`：关节/EE 加速度的平方和；安全/平滑。
- `r_pose_i`：pose head/位姿库对 chunk 末端的预测残差；可用 action 条件 forward 或近似。
- 权重按单任务通道调；不要过拟合一个任务。

### 5.5 best-of-N

- 只在 `CRITICAL_PHASES`；N=2–4。
- 生成不同噪声种子/温度；不要改变 control_space/shape。
- 评分后选 top-1；保留 top-2 作为恢复候选（不执行）。
- 延迟：N 次 forward；如果 `T_infer` 180ms，N=4 就是 720ms；必须算进 `T_eff` 和吞吐。
- 如果 N 倍延迟导致停顿，退回 N=1 + 规则。

### 5.6 早停/恢复

```text
if success_predicate(state) and s_t > τ_s:
    DONE
elif p_t < p_{t-1} - δ for 2 chunks or r_pose stalls > 1s:
    RECOVER
```

- success predicate 必须是可观察的：杯子挂住 2s、插头到位、拉链闭合、碗叠稳。
- 早停能避免“成功后再碰倒”；这是步骤分/成功率都受益的免费增益。
- 恢复：后退 2–3cm，重观测，重规划；最多 2 次；然后放弃子目标。
- 不要在接触段大范围重试；会推飞物体。

### 5.7 人为干扰

```text
intent_conf = P(human take/move/adjust/observe | h_t)
capability_conf = 1 - normalized_action_dispersion
α = sigmoid(a·intent_conf + b·(1-capability_conf) + c)
if α > τ_human: yield
```

- `capability_conf` 可用动作轨迹离散度/价值头不确定性；参考 Capability-Aware Arbitration。
- 让位动作：停止/缓慢后退/保持夹爪；不要继续原 chunk。
- 人离开且场景稳定 1s：重定位任务帧/物体，更新位姿库目标，恢复。
- 过度让位也会丢分；τ_human 在单任务通道调。

### 5.8 校准

- 用单任务通道的 10–20 trials 记录 `(p_final, s, step_score)`。
- 检查 `s_t` 的 Brier/ECE；`p_final` 与 step_score 的 Spearman。
- 如果校准差：降低 `w_s/w_p`，提高 `w_g`（几何残差）/规则；不要盲信价值头。
- 价值头跨任务共享；按任务加 phase embedding，不按任务加独立头。

```yaml
  human: "scripted hand moves cup"
metrics: [success, step_proxy, pose_residual, time_to_success, recovery_count]
```

- `success` 必须可编程/可观察；不能写“挂好”。
- `phases` 与评分步骤对齐；不知道官方步骤时，用语义 phase 代理。
- `demo_subset` 只取成功、无遮挡、单臂/双臂明确的片段。
- `pose_bank` 由 4.1 生成；没有任务帧就不填，回退 VLA。

### 6.2 场景

- G1 URDF + Dex1 + 桌子 + 物体；`unitree_sim_isaaclab`/`unitree_mujoco` 优先。
- 资产缺失用简化几何代理（盒子/圆柱/平面）；不追求照片级。
- 物理参数：摩擦/质量/阻尼用官方/常识初值；用 3 个任务做系统辨识，不追求全局。
- 相机：复现头部双目基线/内参；腕部相机近似；不假设 depth。
- 脚本专家：回放演示 EE 轨迹 + IK；位置/干扰物变体做重定向；未见物体用抓取基元。

### 6.3 5 类泛化

| 类型 | 实现 | 目的 |
|---|---|---|
| 位置 | 物体/受器 xyz/yaw 随机 | 位姿泛化 |
| 干扰物 | 同类/异类物体 | 语义/遮挡 |
| 背景 | 桌布/纹理 | 视觉鲁棒 |
| 未见物品 | 新颜色/形状/尺寸 | 几何泛化 |
| 人为干扰 | 脚本手/遥操作移动物体 | 让位/恢复 |

每类至少 10 trials；不要用 1–2 次下结论。

### 6.4 脚本专家

- 成功演示回放：EE 轨迹 + 夹爪时序；IK 到 G1。
- 变体：对物体位置做相对变换；抓取点用任务帧/几何中心；放置点用任务帧。
- 失败：标记 task card 无效或变体过难；不要让脚本专家失败污染 VLA 评估。
- 脚本专家只用于生成评测场景/配对数据，不作为提交策略。

### 6.5 指标

```text
success_rate
step_proxy = mean(p_final)
pose_residual_median / p95
time_to_success
recovery_count
near_miss_rate
human_yield_success
sim_real_spearman
```

- 记录失败分类：抓空、推飞、差一点、成功后碰倒、人碰崩、超时、接口错误。
- 每个 trial 存视频/动作/位姿残差，便于复盘。

### 6.6 72 小时计划

| 时间 | 任务 | 交付 | 门 |
|---|---|---|---|
| 0–8h | T01/T26/T25 task card + 数据解析 | 3 个 YAML + pose_bank | success predicate 无歧义 |
| 8–24h | 场景 + 回放 + 指标 | 20 trials/任务 | 可重复、失败可分类 |
| 24–40h | 5 类变体 + 脚本专家 | 每类 10 trials | 脚本专家成功率 >80% |
| 40–56h | Base WLA 推理 + adapter | 3 任务基线 | 动作合法、无 NaN |
| 56–72h | sim vs 单任务通道 | Spearman/失败对比 | >0.6 才用于排序 |

如果 72h 不过门：只保留 task card 做单元测试，不用 sim 做决策；把时间转给真机单任务。

### 6.7 sim-real 门

- 3 个任务、每任务 ≥10 trials；比较 sim 与真机的成功率/步骤分排序。
- Spearman >0.6：sim 可用于方法排序/消融。
- ≤0.6：sim 只做接口/安全/单元测试；方法决策回到真机。
- 不要求 sim 绝对值匹配；只要求排序相关。
- SO-101 Bench 显示 sim 可能高估成功率但保留排序；我们仍用保守门。

## 7. 竞赛策略

### 7.1 算术

- 32×10=320 trials；180s/ trial；总上限约 16h 真机（不含 reset）。
- 成功率优先；步骤分 tie-break；早提交 tie-break。
- 单任务通道不计分，但可做 A/B；正式提交次数未知，按保守假设。

### 7.2 任务组合

**方法验证 4 个**：

| 任务 | 时长 | 用途 |
|---|---:|---|
| Hang the Cup | 6.2s | 短、挂钩、位姿尺 |
| Stack Cups | 19.8s | 堆叠、接触、步骤分 |
| Plug In Ethernet | 16.4s | 插入、最后 3cm |
| Toolbox Storage | 37.6s | 长程、恢复、掉步 |

**扩展 8 个**：Zip Up、Open Pill Bottle、Plug Charger、Stack Bowls、Pack Phone、Store Earphones、Organize Pencil Case、Syringe Water Transfer。

**剩余 20 个**：只做 Base/最终版回归，不单独调参。

不要按榜单任务均值排难度；用单任务通道的实测排序。

### 7.3 单任务通道协议

1. 固定 task card、初始位姿、变体顺序。
2. 每个配置 ≥10 trials；A/B 交替，避免漂移。
3. 记录 success、step score、失败分类、延迟、视频。
4. 先跑 Base；再跑 +POSE；再跑 +RUBRIC；不要一次全开。
5. 只比较同一 task card/同一初始分布；否则无效。
6. 通过 G6 才进全量。

### 7.4 提交节奏

| 周 | 目标 | 提交 |
|---|---|---|
| W1 | G0 + adapter + 安全基线 | 早提交可运行版，锁 tie-break |
| W2 | POSE-ANCHOR 离线 + 单任务 | 单任务通道，不正式 |
| W3 | RUBRIC-V + best-of-N | 单任务通道 |
| W4 | PROTO-32 扩 8–12 任务 | 全量前回归 |
| W5 | 32 任务全量 | 正式提交 |
| W6 | 失败分诊 + 修复 top-3 | 最终提交，保留回滚 |

正式提交前检查：token、N 端口、reset 隔离、chunk shape、pivot、gripper 范围、p95 延迟。

## 8. 实验设计与门

### 8.1 离线

| 实验 | 数据 | 指标 | 门 |
|---|---|---|---|
| 位姿库 | 32 任务成功演示 | 留出 episode 的相对位姿误差 | 中位数 <1cm/5° |
| pose head | 演示 EE 位姿 | 平移/旋转误差、动作 MSE/DTW | 比 Base 降 >10% |
| value head | phase/终局 | 排序准确率、Brier/ECE | 排序 >70%，ECE <0.1 |
| 检索 | 初始位姿/语言 | top-k 位姿误差 | top-3 中位数 <1cm/5° |

### 8.2 仿真

| 实验 | 变体 | 指标 | 门 |
|---|---|---|---|
| task card | 3 任务 ×5 类 | 成功率/步骤代理 | 脚本专家 >80% |
| Base | 3 任务 | 成功率/失败分类 | 可重复 |
| +POSE | 3 任务 | near-miss/恢复 | +5pp 或残差降 |
| +RUBRIC | 3 任务 | best-of-N 增益 | +5pp，延迟可接受 |
| sim-real | 3 任务 | Spearman | >0.6 |

### 8.3 真机单任务

| 实验 | trials | 指标 | 门 |
|---|---|---:|---|
| Base | 20/任务 | success/step | 基线 |
| +POSE | 20/任务 | success/step/残差 | 2/3 任务 +5pp |
| +RUBRIC | 20/任务 | success/step/延迟 | 2/3 任务 +5pp |
| 人为干扰 | 10/任务 | 让位/恢复 | >80% |

### 8.4 全量

- 32 任务 ×10；先 Base，再最终；不要在同一次提交混方法。
- 指标：总平均成功率、总平均步骤分、失败分类、超时、接口错误。
- 门：最终不低于 Base；步骤分升；无安全/接口回归。

### 8.5 消融

| 消融 | 目的 |
|---|---|
| pose head only | 位姿是否真的有增益 |
| value head only | 过程分是否真的有增益 |
| pose+value | 是否互补 |
| N=1/2/4 | best-of-N 的边际 |
| H=8/12/24 | 吞吐/反应 trade-off |
| 双目/腕部/两者 | 多尺度必要性 |
| 早停开/关 | 成功后碰倒的比例 |
| human gate 开/关 | 让位/恢复 |

### 8.6 门 G0–G8

| 门 | 假设 | 指标 | 杀掉条件 |
|---|---|---|---|
| G0 | 接口/端口/adapter 正确 | 100/100 合法；p95 <500ms；reset 隔离 | 串状态/动作被拒 |
| G1 | 位姿库可检索 | 留出误差 <1cm/5° | >2cm/10° |
| G2 | 位姿头有增益 | MSE/DTW 降 >10% | 无增益/拖慢 >20% |
| G3 | 价值头可校准 | 排序 >70%；ECE <0.1 | 接近随机 |
| G4 | best-of-N 值得 | +5pp，延迟可接受 | 无增益/N 倍延迟 |
| G5 | 仿真能排序 | Spearman >0.6 | 只做单元测试 |
| G6 | 单任务真机有增益 | 2/3 任务 +5pp | 无/负增益 |
| G7 | 全量不回归 | 成功率不低于 Base；步骤分升 | 回归 >2pp |
| G8 | 人为干扰可恢复 | 让位/恢复 >80% | 碰撞/抢物/长停 |

## 10. 风险与合规

### 10.1 风险表

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 位姿头无增益 | 中 | 高 | G2 杀掉；回退 Base/IBVS |
| 价值头不校准 | 高 | 高 | 只用排序/规则；单任务校准；ECE 门 |
| 任务帧标注错 | 中 | 高 | 3 任务人工抽检；残差监控 |
| 双目在 1m 精度不够 | 高 | 中 | 只做粗；腕部 IBVS |
| 腕部外参未知 | 高 | 中 | 手眼标定/IBVS 免外参 |
| 吞吐不够 | 高 | 高 | H≥N·f·T_infer；加卡/换小模型 |
| best-of-N 延迟 | 中 | 高 | 只关键相位；N=2；异步 |
| 人为干扰误判 | 中 | 中 | 保守让位；恢复重定位 |
| 单模型合规 | 中 | 致命 | C1+C2；回退开关；不加载第二模型 |
| sim-real 不相关 | 中 | 中 | G5 只做单元测试 |
| 官方评分未知 | 高 | 中 | phase 代理；不宣称官方分 |
| 榜单误导 | 高 | 中 | 只当预览；单任务通道决策 |

### 10.2 合规清单

- [ ] 提交只有一个 checkpoint；pose/value 头在同一文件。
- [ ] 不加载第二个策略/VLM reward/6D pose 网络。
- [ ] IBVS/规则是确定性控制器，不训练。
- [ ] action shape/control_space/token/pivot 与官方一致。
- [ ] N 端口独立；reset 只清本端口。
- [ ] 数据/模型许可保留 NOTICE。
- [ ] 人为干扰下安全优先，不碰撞/不抢物。
- [ ] 不把预览榜单当实测；正式结论来自单任务/全量。
