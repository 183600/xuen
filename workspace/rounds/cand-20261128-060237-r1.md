### 第 6 轮灵感驱动研究记录

**灵感词**：产学研合作、痛点分析

**继承关系**：第 5 轮 CADVS-v5（IP-493~496）以「认证的生成式执行」（CGE）把提议器换成条件流匹配、记忆升级为 LMEM-v2、人因升级为情感调制，执行集 Exec_CADVS-v5 ⊆ Exec_CADVS-v4 ⊆ … ⊆ Exec_v29。v5 的最大风险 R57 是**记忆固化自指回路**：提议器在自己铸证的片段上训练，缺乏外部真值，可能学会博弈证书门。本轮两个灵感词不是新的 ML 技术，而是**方法论级**输入：「产学研合作」提供**外部真值与社会性分权**，「痛点分析」提供**停止无节制扩张、按真实部署痛点收敛**的准则。二者合起来把 v5 从「更强的生成式认证」推进到「可部署、可外部审计、可收敛的认证执行」（Deployable Certified Execution, DCE），形成 CADVS-v6（IP-497~500）。本轮自律（比 v5 更严）：**不新增硬门、不新增安全模块、不新增复杂网络**，只加「认证协议 / 审计基础设施 / 治理准则 / 一致性套件」四类非能力性组件；执行集 Exec_v6 ⊆ Exec_v5 由「证书验签更严 + 高风险外部加签 + DCK 一致性等价」保证，并首次**主动退役**两个低价值旧接口以净降维护负债。

**直觉与动机**：

1. **产学研合作 → 把「谁来认证」从代码问题升级为制度问题：三权分立认证（TSC）**。v5 的证书由同一个系统自己产生、自己消费，R57 的根因是**提议权与认证权同体**。现实中「产学研」之所以能提高可信度，不是因为某一方更聪明，而是因为**角色分离 + 交叉验证 + 可追责**：产业方出场景/数据/部署（提议），高校出理论/红队/独立复现（审计），研究院/标准机构出规范/一致性认证（裁定）。映射到框架：引入三个不可合并的角色——提议方 P（运行 FMPP/LMEM）、认证方 C（独立持有冻结门 τ⁴ 与签名私钥 sk_C）、审计方 A（高校/标准机构，持有外部真值与红队）。证书从「自签」升级为「双签/三签」：σ_P 声明轨迹与上下文，σ_C 声明七门通过，σ_A 仅对高风险任务加签。**定理 9（分权认证不可自证）**：只要 sk_C 不在提议方可达范围、门代码签名冻结，则任何进入 Exec_v6 的轨迹必须携带有效 σ_C；提议方的固化只能改 θ_FM，无法凭空铸证。这把 R57 的「自我背书」在结构上拆成「可归因的三方行为」。

2. **痛点分析 → 用「痛点账本 + 维护负债预算」给研究循环踩刹车**。前五轮每轮加约 4 个 IP，框架已从 v1 膨胀到 v5，R52（锚点维护负债）与 R59（接口漂移）本身就是被忽略的痛点。痛点分析要求：先系统采集三类利益相关方的真实痛点（产业：集成成本、停机、验收周期；高校：可复现性、理论可检验性；研究院/监管：合规证据、可审计性），量化排序后，**只允许关闭 Top-K 痛点，禁止「因为能做所以加模块」**。引入痛点账本 PPL 与**维护负债预算**：新模块 M_new 只有在「闭合痛点收益 ΔΠ_closed > λ_debt·ΔD_maint」时才被接受（痛点/负债比准则）。这给研究循环一个 Lyapunov 式收敛论证（定理 10）：未覆盖痛点势函数单调下降，直到 Pareto 前沿，循环自然停在「可部署」而非「更复杂」。

3. **两者合流 → 外部真值不是又一个模型，而是一条可审计证据链：证书透明日志（CTL）+ 部署一致性套件（DCK）**。产学研要落地，必须回答「外部真值从哪来、怎么被所有方核验」。引入 append-only Merkle 证书透明日志：每次认证写入 (H(x), c_hash, 门结果向量 g, σ_P, σ_C, [σ_A], t, ver)，任何一方可做 inclusion/consistency proof；事后结局验证（产业 outcome）回填后即可定位是「提议错、认证错、审计漏还是规范本身错」。再配 DCK：把门语义、阈值 τ⁴、接口 schema 版本固化成可执行一致性测试与 golden 轨迹，高校定规范、产业实现、研究院签发一致性证书。DCK 同时是 R59 接口漂移的工程解。

**关键洞见**：v5 回答「生成式提议如何不破坏证书边界」；v6 回答「证书边界由谁认证、外部真值如何进入、研究循环如何停止膨胀」。七硬门 kc_v5 原样复用（τ⁴ 冻结、τ⁵=γ·τ⁴ 调制），本轮不碰安全性内核，只在**认证层、审计层、治理层**加三个非能力性组件。Exec_CADVS-v6 ⊆ Exec_CADVS-v5 由「双签验签（更严）+ 高风险外部加签 + DCK 等价类」保证；同时用 PPL 主动退役/合并两个低价值旧接口（候选：v4 的解析边际内插缓存、v5 的 η_flow 独立阈值），首次实现维护负债净下降。

**形式化目标（增量）**：
1. 角色与密钥：P/C/A 三方；sk_C 由独立 HSM 持有，门代码 + τ⁴ 的哈希 h_gate 由 C 签名并写入 CTL 创世块；P 只能提交待签提议，不能写 CTL 的认证条目。
2. 证书 Cert(x,c) = (H(x), c_hash, g(x,c), σ_P, σ_C, [σ_A], t, ver, ct_idx)；Verify 要求 g 全过 ∧ 三方验签全过 ∧ CTL inclusion proof 有效 ∧ h_gate 与创世承诺一致。
3. PPL：p_i=(role, cat, f, s, d, c_cost, M_aff, ev)；Π(p)=w_role·(f·s·c_cost)/(d+ε)；Top-K 选取；覆盖矩阵 cov(M_j,p_i)。
4. 维护负债预算：接受 M_new 当且仅当 ΔΠ_closed(M_new) > λ_debt·ΔD_maint(M_new)；否则拒绝，或要求先退役旧模块。
5. 定理 9（分权认证不可自证/EUF-CMA 归约）、定理 10（痛点驱动收敛：势函数单调下降）、定理 11（外部真值可归因性）、定理 12（DCK 接口等价/漂移可检测）。
6. Exec_v6 = {x : Verify(Cert(x,c))=1 ∧ x∈supp(π_FM) ∧ DCK_ver 匹配} ⊆ Exec_v5。

**本轮最大风险**：**制度性失效/共谋俘获**——三权分立与外部真值全部依赖「角色不共谋 + 密钥不泄露 + 痛点账本不被利益相关方操纵」，一旦产业方与认证方合谋、或标准机构被俘获，外部真值就退化为橡皮图章，审计日志只能证明「大家签过字」而不能证明「签得对」。

### IP-497 TSC：三权分立认证协议（准入时域；控制环零改动）

```python
@dataclass
class TriPartyCertification:
    """TSC：提议方 P 提交待签包；认证方 C 用 HSM 内 sk_C 签门结果；
    审计方 A 对高风险任务加签。红线：P 永远拿不到 sk_C。"""
    p_verifier: Any                 # pk_P
    c_hsm: Any                      # 仅暴露 sign(g_hash) 接口，私钥不出 HSM
    a_verifier: Any                 # pk_A（高风险才用）
    ctl: CertificateTransparencyLog
    gate_commitment: bytes          # H(code_gate||tau4||ver)，创世块锚定

    def issue(self, x, c, gate_results, high_risk: bool) -> Cert | None:
        h_x, h_c = H(x), H(c)
        if not all(gate_results):                 # fail-closed
            return None
        payload = H(h_x ‖ h_c ‖ gate_results ‖ self.gate_commitment)
        sig_p = sign(sk_P, payload)               # P 声明“我提交了这组输入”
        sig_c = self.c_hsm.sign(payload)          # C 声明“七门确实通过且门版本正确”
        sig_a = sign(sk_A, payload) if high_risk else None
        ct_idx = self.ctl.append(H(payload ‖ sig_p ‖ sig_c))
        return Cert(h_x, h_c, gate_results, sig_p, sig_c, sig_a, now(), VER, ct_idx)

    def verify(self, cert: Cert) -> bool:
        payload = H(cert.h_x ‖ cert.h_c ‖ cert.g ‖ self.gate_commitment)
        ok = (all(cert.g)
              and verify(pk_P, payload, cert.sig_p)
              and verify(pk_C, payload, cert.sig_c)
              and (cert.sig_a is not None or not self.was_high_risk(cert))
              and (cert.sig_a is None or verify(pk_A, payload, cert.sig_a))
              and self.ctl.inclusion_ok(cert.ct_idx, cert))
        return ok
    # 注：P 若尝试自签，因无 sk_C 无法构造 sig_c ⇒ Verify 失败 ⇒ 不进 Exec_v6
```

### IP-498 PPL：痛点账本与优先级（离线/治理，周期级）

```python
@dataclass
class PainPointLedger:
    """PPL：三方痛点采集 → 评分 → 覆盖矩阵 → Top-K 与负债预算。
    目的不是加能力，而是决定“这轮到底该不该加、先加什么、能不能退役”"""
    entries: list
    theta_cov: float = 0.6
    lambda_debt: float = 1.0

    def priority(self, p) -> float:
        return p.w_role * (p.f * p.s * p.c_cost) / (p.d + 1e-6)

    def topk_uncovered(self, k: int = 5) -> list:
        unc = [p for p in self.entries
               if max(cov(m, p) for m in MODULES) < self.theta_cov]
        return sorted(unc, key=self.priority, reverse=True)[:k]
```

```python
@dataclass
class CertificateTransparencyLog:
    """CTL：Merkle append-only 日志。写入只追加；任何一方可验证包含与一致性。

    tree: Any
```

### IP-500 DCK：部署一致性套件（构建/上线门，非运行时门）

```python
@dataclass
class DeploymentConformanceKit:
    """DCK：把门语义/τ⁴/接口 schema 固化为可执行一致性测试。
    高校定 Spec，产业实现，研究院签发一致性证书。DCK 失败 ⇒ fail-closed 不上线。"""
    spec_version: str
    golden_trajectories: list
    checker: Any

    def run(self, deployed_gate_impl) -> ConformanceReport:
        report = self.checker.compare(deployed_gate_impl, REFERENCE_GATE,
                                      self.golden_trajectories)
        # 语义等价（在 golden 集上）+ 接口 schema 哈希匹配 + 阈值 τ⁴ 哈希匹配
        return report

    def dck_ver(self, x, deployed_gate_impl) -> bool:
        if not self.last_report.passed:
            return False                       # 未过一致性 ⇒ 一律拒绝（fail-closed）
        return self.checker.equivalent_on(x, deployed_gate_impl, REFERENCE_GATE)
```

### IP-491 扩展 CERTCALC-v6：新增定理 9~12（离线理论）

```python
# 定理 9：分权认证不可自证（对 R57 的结构性回应）
def theorem_separation_of_powers() -> str:
    """
    定理 9：设签名方案 EUF-CMA 安全；(S1) sk_C 仅存于 P 不可达的 HSM；
    (S2) 门代码与 τ⁴ 冻结且 h_gate 经 C 签名锚定于 CTL 创世块；
    (S3) Verify 要求有效 σ_C 且 CTL inclusion 通过。
    则对任意 P 可执行的策略（含固化后的 θ_FM），其自铸证书被接受的概率 ≤ negl(λ)。
    即 Exec_v6 中的轨迹必然经过独立认证方；P 的固化只能改提议分布，不能扩执行集。
    证明：若 P 能产出被接受的 Cert 而未经 C 签名，则构造 EUF-CMA 伪造者，矛盾。∎
    诚实边界：定理只保证“无 sk_C 不可伪造”，不保证 C 本身正确或三方不共谋。
    """
    return "Proven (under S1-S3); collusion excluded by assumption"

# 定理 10：痛点驱动的循环收敛
def theorem_pain_driven_convergence() -> str:
    """
    定理 10：设痛点集合有限、评分 Π 在单轮内平稳；每轮仅接受满足
    ΔΠ_closed > λ_debt·ΔD_maint 的变更，且被拒变更不改变 Φ。
    则 Φ_t = Σ_{Uncovered} Π 单调不增；每次接受严格下降；故 Φ_t 收敛。
    在收敛点，不存在同时“闭合痛点且满足负债预算”的可行变更（Pareto 最优）。
    证明：Φ_{t+1} = Φ_t − ΔΠ_closed ≤ Φ_t，有下界 0，单调收敛。∎
    诚实边界：新痛点会随部署涌现，故为“单 epoch 收敛”，非全局终止；Π 可被策略性操纵（见 R62）。
    """
    return "Proven (per-epoch); global termination not claimed"

# 定理 11：外部真值可归因
```

## 4. 正确性论证（增量更新）

### 定理 9（分权认证不可自证）

**陈述**：在 (S1) sk_C 仅存于 P 不可达 HSM、(S2) 门代码与 τ⁴ 冻结且 h_gate 经 C 签名锚定、(S3) Verify 要求有效 σ_C 与 CTL inclusion 下，任意 P 侧策略（含固化后 θ_FM）产出被接受证书的概率 ≤ negl(λ)。

**证明**：假设 P 产出被接受 Cert 而无 C 签名，则其构造了 payload 上的有效 sk_C 签名，构成 EUF-CMA 伪造，与签名安全矛盾。又因 Verify 含 g 全过与 DCK，P 的固化只改提议分布 supp(π_FM)，不改门谓词，故不能扩执行集。∎

**诚实边界**：定理不覆盖 C 实现错误、HSM 供应链攻击、三方共谋；这些是 R60/R61，属制度与供应链风险，不能由密码学单独消除。

### 定理 10（痛点驱动收敛）

**陈述**：有限痛点集、单轮评分平稳、仅接受 ΔΠ_closed > λ_debt·ΔD_maint 的变更，则 Φ_t 单调不增并收敛；收敛点对 (Π, D_maint) 为 Pareto 最优。

**证明**：Φ_{t+1} = Φ_t − ΔΠ_closed ≤ Φ_t，且有下界 0，故收敛；收敛时任何可行变更不满足预算不等式，即不存在同时降痛点、守预算的改进，Pareto 最优。∎

**诚实边界**：新痛点随部署涌现，结论为单 epoch；Π 可被策略性虚报/瞒报（R62）。

### 定理 11（外部真值可归因）

**陈述**：给定不可抵赖 CTL 与独立结局标签，审计采样率 q，已认证但失败样本的误归因概率 ≤ (1−q)+δ_audit。

**证明**：CTL 固定 (输入, 门结果, 签名)；结局标签独立；未抽样部分最多贡献 1−q 的不可判定质量，抽样部分以 δ_audit 的复核错误率归因。∎

**诚实边界**：三方共谋使归因失效；「规范缺陷」类失败应回流 PPL，且规范修订需 C+A 多签，P 无权单方面改门。

### 定理 12（DCK 等价与漂移可检测）

**陈述**：若 G_ref 与 G_dep 在 D_test 上一致且 TV(D_op, D_test) ≤ ε，则运行分布上分歧率 ≤ ε+δ_test；DCK 未通过则部署被拒。

**证明**：全变差耦合给出分布间分歧界；未通过分支由构造直接 fail-closed。∎

**诚实边界**：依赖 D_test 对 D_op 的覆盖假设；规格-现实差距为 R65。

### 定理 v6（可部署认证执行总装）

**陈述**：在 v5 假设 (B1)~(B7) 及新增 (B8) 签名 EUF-CMA、(B9) HSM 私钥不可导出、(B10) DCK 测试覆盖假设下：

(ii) 分权不可自证（定理 9）：R57 的自我背书在结构上被拆解为可归因三方行为；
(iii) 循环按痛点势函数收敛（定理 10），并首次净降维护负债；
(iv) 已认证失败可归因（定理 11），规范缺陷回流 PPL 而非由提议方私自改门；
(v) 部署门与参考门在覆盖假设下等价（定理 12），接口漂移可检测（R59 工程解）。

**证明**：(i) 由 Verify 新增合取项与 DCK 合取项；(ii) 定理 9；(iii) 定理 10；(iv) 定理 11；(v) 定理 12。∎
