## 1. 直觉与动机（两个灵感的碰撞）

### 灵感 1（自主导航 → 不是「走到桌前」，而是「导航到可操作的构型与下一个得分点」）

**直觉**：在桌面操作赛里，「导航」最容易被误解成移动底盘走到桌边。但数据告诉我们另一件事：多数任务基座静止，然而 **18/32 任务的高度跨度 >0.05（可能来自跨 episode 的高度差异，也可能含帧级变化）、22/32 任务的 hmin<0.70、7/32 任务的基座平移指令幅值 >0.1**（F21）。也就是说，真正的「导航」发生在**工作空间构型**里：把基座/高度/腰部移动几厘米，换取「够得到、看得见、不撞桌」；以及在**任务里程碑图**里，决定下一步追哪个得分点、什么时候回退。多数基线把 `action.pivot` 直接输出零（F20），等于放弃了这条通道。核心反直觉点：**桌面操作的导航不是长距离 locomotion，而是短距离的「可操作集重定位」；最好的导航动作常常是 2cm 的基座/腰部调整，而不是几米。**

**严谨定义**：把自主导航实例化为两个耦合层。

1. **任务图导航（milestone navigation）**：给定任务得分点构成的有向图 `M = (V, E)`（`V` 为得分点/里程碑，`E` 为允许的推进顺序，来自 F17 的逆向清单），当前观测 `s_t`，进度估计 `p_t(k) = P(m_k achieved | s_t)`。导航策略在每一步选择「继续当前里程碑 / 回退到上一个已验证里程碑 / 重试 / 结束」：
   `π_task(a_task | s_t, p_t, history)`。
   目标不是最大化单步动作似然，而是最大化期望步骤分：
   `max E[Σ_k w_k 1(m_k achieved)] - λ_t T - λ_r Risk`。
2. **工作空间导航（workspace navigation）**：构型空间 `C = SE(2) × [h_min,h_max] × Q_waist`（基座平面位姿 × 高度 × 腰部）。对候选构型 `c ∈ C` 定义代价
   `J(c) = w_r R(c) + w_v V(c) + w_c C_col(c) + w_b B(c) + w_t ||c - c_0||`，
   其中 `R` 为 IK/可达残差，`V` 为可见性/遮挡代价，`C_col` 为自碰撞/桌面净空，`B` 为静态平衡裕度，最后一项把构型拉回任务标称 `c_0`（防止无意义的乱动）。在 `reset()` 与事件触发时求解
   `c* = argmin_{c∈C_safe} J(c)`，只有 `J(c*) < J(c_0) - δ` 才移动。
3. **退化情形**（必须写进实现）：若基座被禁止 → `C` 退化为高度/腰部；若腰部语义未验证 → 只保留高度；若全部被锁 → 退化为纯任务图导航 + 主动视角（头部/相机）。这样 AWN 不把方案绑死在一个未核实的接口假设上。

**为什么是现在**：v1.1 的胜负手在数据引擎；但数据引擎解决「策略知道什么」，不解决「策略在评测时把自己摆在哪里、追哪个点」。F21/F22 首次量化了执行侧的两块浪费：构型通道被闲置、成功轨迹里的空抓/重抓没有被利用。这正是本轮从「数据侧」转向「推理期自主」的理由。

### 灵感 2（可重构机构 → 不是改硬件，而是让同一模型重构「有效末端/手臂/姿态」）

**直觉**：题目接口只暴露 `gripper 1+1`（F23），并不给我们控制每根手指；所以「可重构机构」在本题里不是改连杆/换夹爪，而是重构**有效操作构型**（effective manipulation configuration）：用哪只手臂、从哪个方向接近、抓物体哪个高度/哪个面、是否用另一只手辅助、基座/腰部如何配合。人类做拉链、插充电器、倒药时，本来就会换抓法；单一策略把所有抓法平均成一个「四不像」的均值，是弱任务的根因之一。更关键的是，F22 表明成功示范内部本来就有空抓→重抓段：**重配置信号不是我们凭空造的，数据里就有。** 核心反直觉点：**「可重构机构」在这场比赛里主要是一个离散隐变量问题，不是硬件问题；收益来自不让一个单峰策略去平均互相不兼容的抓取模式。**

**严谨定义**：定义离散模式变量
`m = (arm, grasp_frame, approach_dir, grasp_height, support_hand, torso_assist) ∈ M_modes`，
其中 `grasp_frame` 是物体坐标系下的抓取帧（接近轴 + 夹爪闭合轴），`approach_dir` 是接近方向，`support_hand` 表示是否用另一只手稳定物体，`torso_assist` 表示是否用腰部/高度辅助。学习一个**模式条件化**的单模型策略
`π_θ(a | o, l, m)`，
`m` 通过语言后缀（如「[grasp: top, arm: right, height: high]」）或一个可学习 embedding 注入；backbone 与动作头仍是一个模型。模式发现用示范段聚类：特征取 `(arm, gripper width trajectory, EE approach direction, contact point relative to object, torso posture)`，得到每任务族的 `K` 个模式；用 VLM/LLM 给模式起名以便人工校对。模式选择与重配置：
`m* = argmax_m U(m | o) = P_success(m | task, o) · Affordance(m, o) - λ_fail 1(m ∈ Failed)`，
在 `reset()` 选一次；当检测到空抓/滑落/进度停滞时，把当前模式加入 `Failed`，回退到最近一个已验证节点（knot），再选下一个模式。**单模型边界**：模式选择器是规则/小分类器，不是第二个动作策略；若组委会仍认定其为第二模型，降级为「语言后缀 + 纯端到端」，不改主链。

### 合流：导航决定「在哪、追哪个点」，重构决定「用哪种构型去做」

- **数据引擎（v1.1）** 提供：任务标称构型 `c_0`、模式先验 `P_success(m|task)`、空抓/重抓段、得分点清单。
- **自主导航（I10）** 在推理期决定：当前该追哪个里程碑、基座/高度/腰部该摆在哪。
- **可重构操作（I11）** 在推理期决定：用哪种手臂/抓取帧/接近方向/辅助方式去执行。
- 两者都不新增训练数据、不新增第二个动作模型，属于「推理期构型自主」；与 v1.1 的数据侧组合拳互补，而不是替代。

## 2. 对 v1.1 痛点的增量修订

- **P2（泛化缺口）** 补充：五轴之外还有「工作空间/高度/遮挡」这一执行侧泛化轴；AWN 直接针对它。
- **P4（无触觉）** 补充：AWN/RMC 只能靠视觉 + 本体感受；接触力仍不可观测，所以构型动作必须保守，不能假装有力反馈。
- **P5（时间压力）** 补充：导航/重构会消耗 episode 预算；必须低频、带迟滞、可随时放弃（anytime）。
- **P7（先手窗口）** 补充：AWN/RMC 是推理期/数据工程，成本低，适合在等真机排期时先做 L0。
- **P8（示教质量）修正**：v1.1 说「全成功、无失败示教」不准确。episode 级全成功，但成功轨迹内部含空抓/重抓段（F22）。这既降低 I5 的合成压力，也给 I11 提供真实的模式切换标签。
- **新增 P11（构型通道浪费）**：`action.pivot` 被基线输出零，而演示中高度/基座并非恒定（F21）。
- **新增 P12（模式纠缠）**：单一单峰策略会把不兼容的抓取模式平均掉，弱任务因此学不会「换一种抓法」。
- **新增 P13（接口语义风险）**：`pivot` 的 `p3–p5`、base 是否允许运动、height 范围均未公开；未验证前不能上计分通道。
- **新增 P14（重构安全风险）**：导航/重构可能造成失稳、碰撞、动作不连续，触发可信度审查（F26）。

## 3. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

- **Q9（工作空间导航）**：在只有单目/双目 RGB、无触觉、`pivot` 语义部分未知的条件下，哪些构型维度（height / waist / base）可以被安全地用于「够得到/看得见」？AWN 的代价函数 `J(c)` 中 `R/V/C_col/B` 如何用官方 G1 运动学与少量真机日志标定？在哪些任务族上期望收益最大（OrganizeTools、OrganizeBookshelf、PickOutBatteries、Unlock…）？
- **Q10（可重构操作）**：从示范中能稳定发现多少个可解释的操作模式？模式条件化（语言后缀 vs embedding）能否在单模型内提升弱任务（ZipUp、PlugCharger、PourOutMedicine）？空抓后「同模式换抓取点」与「换模式/换手」的收益交叉点在哪里，如何用视觉置信度做准入？
- **Q11（导航-重构协同与安全）**：什么时候应该先导航（改变构型）而不是先重构（换抓法）？两者同时触发时如何避免振荡、延迟尖峰与不可逆动作？在 320 个计分 trial 的统计功效下，哪些增益值得占用 L2 真机预算？

## 4. 设计原则（新增 PR6–PR8，其余保留）

- **PR6 接口语义闸**：`pivot` 的未验证维度（尤其 `p3–p5`、base 平移）不得直接进入计分通道；先做单维探针，确认语义、限位、方向、绝对/增量，再逐维启用。默认输出任务标称构型 `c_0`，不是全零。
- **PR7 可逆构型律**：任何导航/重构动作必须存在安全回归路径：限速、限幅、迟滞、超时回标称；检测到平衡/碰撞风险立即回 `c_0`。不可逆的大幅 base 运动默认禁止。
- **PR8 先验回归律**：只有当 `J(c*) < J(c_0) - δ` 或 `U(m*) > U(m_0) + δ` 时才偏离标称；没有足够证据就保持标称。与 PR1 互补：PR1 管「做不做」，PR8 管「改不改构型」。
- PR1–PR5 保留（第 1/2 轮 §4）。

## 6. 本轮最大风险

**一句话**：本轮最大风险是把「未验证的 `pivot`/base 语义」当成自由导航通道——一旦 base 运动被禁止、`pivot` 是绝对目标或 `p3–p5` 并非腰部，AWN 可能把机器人推出工作空间或失稳，而每任务仅 10 次 trial 的低分辨率会让错误在早期很难被统计发现；因此必须先探针、默认标称、可逆构型、L0/L1 闸后再放量。

- **修剪**：I7 维持待裁撤；若 base 运动被禁止，AWN 降级为 height/waist-only；若腰部未验证，降级为 height-only；若 RMC 模式条件化被判定为第二模型，降级为语言后缀。

## 2. I10 自主任务-工作空间导航（AWN）★★★★

- **动机**：① `pivot` 通道被基线输出零（F20），而演示中高度/基座/躯干并非恒定（F21）；② 泛化轴中的位置/高度/遮挡会直接改变「够不够得到、看不看得见」，纯手臂策略无解；③ 步骤分制奖励「推进到下一个得分点」，而单峰策略容易在局部失败后卡死，不会主动回退/换构型（F24）；④ 人为干扰可能把物体移出可达区，需要「让位/重定位」而非硬抓。
- **与现有方案差异**：直接 SFT 队伍只出双臂+夹爪，`pivot` 输出零/常数；加增广的队伍改变训练分布，但推理时仍不会主动改变构型。AWN 是**推理期**的构型导航：在任务图 `M` 上选里程碑，在工作空间 `C` 上选构型，二者用同一个进度/风险信号驱动。它不新增动作模型，属于同一 PolicyService 内的模型基控制器（PR2 边界需书面确认；降级预案见下）。
- **技术可行性**：中-高。`J(c)` 的四项都可用现成工具离线算：`R` 用 G1 FK/IK（F25），`V` 用目标分割 + 相机投影/遮挡近似，`C_col` 用 G1 MJCF 自碰撞/桌面平面，`B` 用 CoM 投影到支撑多边形；在线只做小网格搜索（5×5 基座 × 3 高度 × 3 腰部 ≈ 225 个候选，2–5Hz 足够），不进入每步热路径。
- **所需资源**：1×24GB GPU 用于离线 IK/渲染/审计；1–2 人周工程；无新增训练数据；在线 CPU 即可（与 I6 共享 backend）。
- **落地步骤**：
  1. **探针**（最高优先）：默认 `c_0 = [0,0,0,0,0.15,0,0.738]`（来自演示统计，F21），逐维施加 ± 小量，记录 base/waist/height 响应；确认 `p3–p5` 语义、绝对/增量、限位、方向。未通过前只输出 `c_0`。
  2. **构型先验表**：按任务统计 `c_0`、height 分位数、p4 均值、base 使用率（F21）；作为 `J` 的先验项与安全范围。
  3. **离线代价图**：对 32 任务 × 位置/高度扰动网格，算 `R/V/C_col/B`；找出「固定构型不可达但 AWN 可达」的任务族。
  4. **在线导航器**：`reset()` 选一次；进度停滞/目标丢失时事件触发；带迟滞与超时回标称（PR7）。
  5. **安全 shield**：平衡/碰撞/限幅/延迟四道门；触发即回 `c_0`，不尝试「硬救」。
  6. **消融**：static vs height-only vs height+waist vs full；每维单独开关。
- **风险**：① `pivot` 语义未验证 → 探针前不上计分通道，默认标称；② base 运动可能被禁止或导致失稳 → 默认不启用 base，优先 height/waist；③ 导航耗时挤占 episode 预算 → anytime + 迟滞 + 只在 L0 显示强收益时启用；④ 评测端相机内参与数据集不一致 → 可见性代价用相对量，不依赖绝对深度；⑤ 单模型边界 → 若模型基控制器被判定违规，降级为「训练时辅助监督」（用 AWN 目标作辅助标签/条件，推理纯端到端）。

## 3. I11 可重构操作构型（RMC）★★★★

- **动机**：① 接口只给 `gripper 1+1`（F23），但任务需要不同抓法（顶部抓杯、侧向插充电器、倒药瓶、拉拉链）；单峰策略会把不兼容模式平均掉（P12）；② 成功示范内部已有空抓→重抓段（F22），说明「换抓法」是数据里真实存在的行为，不是我们发明的；③ 弱任务（ZipUp、PlugCharger、PourOutMedicine、HangCup）常败在第一次抓取/接触，而不是后段搬运；④ 步骤分制下，一次空抓后能重配置，往往比整段重来更省步骤分。
- **与现有方案差异**：纯 SFT 用一条指令 + 一个动作分布，模式不可控；任务特定脚本队伍为每个任务写死抓法，泛化差且违反单模型边界。RMC 在**同一模型**内加一个离散模式条件 `m`，并在失败后显式重选；模式来自示范聚类，不是手写。
- **技术可行性**：中-高。模式发现是离线无监督/弱监督；模式注入可用语言后缀（零架构改动）或 embedding（小改）；模式选择器是规则/小分类器（非动作策略）；空抓检测用 `gripper 闭合 + 腕部物体掩码不增 + EE 位移小`，复用 `obs_delta_indices` 历史栈。
- **所需资源**：模式发现 1 GPU 日；模式条件化 LoRA 1×24GB（官方默认配置即可，F11）；2 人周工程；在线无额外模型调用（模式 token 随语言/条件进入同一前向）。
- **落地步骤**：
  1. **模式发现**：对示范段提特征 `(arm, gripper width trajectory, EE approach dir, contact point relative to object, torso posture)`，聚类得 `K` 个模式；VLM/LLM 命名 + 人工抽检 5%。
  2. **模式库**：按任务族统计 `P_success(m|task)`、平均步数、空抓率；从 110 语料/DiverseManip 扩充稀有模式（F27）。
  3. **模式条件化训练**：baseline vs language-suffix vs embedding；在 3 个弱任务 + 2 个对照任务上做 LoRA。
  4. **空抓检测与重配置**：检测到空抓 → 当前模式入 `Failed` → 回退到最近验证 knot → 选下一模式；带迟滞，避免来回换。
  5. **消融**：模式条件开/关；重配置开/关；模式标签来源（聚类 vs 手标 vs 无）；选择器（规则 vs 学习）。
  6. **L2 真机**：只测 L0/L1 联合排名 top 2–3 的组合，每任务 ≥2 次。
- **风险**：① 模式聚类不纯/不可解释 → VLM 命名 + 人工抽检 + 只保留高纯度模式；② 语言后缀改变输入分布、模型不遵循 → 先做 L0 遵循率测试，不行改用 embedding；③ 重配置振荡/动作不连续 → 迟滞 + 最小驻留步数 + 平滑过渡；④ 被判定为第二模型 → 模式选择器降级为确定性规则/语言后缀；⑤ 空抓检测误报 → 置信门控 + 只在低风险段触发。

### 5.1 AWN：构型导航与安全 shield

```python
# c = (x, y, yaw, height, waist) 的可验证子集；未验证维度固定为 c0
class WorkspaceNavigator:
    def __init__(self, task, kin, safety):
        self.c0 = TASK_NOMINAL[task]          # 来自 F21 的演示统计
        self.dims = VERIFIED_DIMS             # {height} / {height,waist} / {base,height,waist}
        self.c = self.c0
        self.hold_until = -1

    def reset(self, obs):
        self.c = self.c0
        cand = self.choose(obs, self.c0)
        if cand is not None:
            self.c = cand
        self.hold_until = obs.t + HOLD_STEPS   # 导航后至少保持一段，防振荡

    def choose(self, obs, c0):
        best, best_J = None, self.cost(obs, c0)
        for c in grid(self.dims, around=c0):          # 小网格，2–5Hz
            if not self.safety.feasible(c, obs):      # 限位/自碰撞/桌面/平衡
                continue
            j = self.cost(obs, c)
            if j < best_J - DELTA:                    # PR8：无足够收益就回标称
                best, best_J = c, j
        return best

    def cost(self, obs, c):
        return (W_R * ik_residual(c, obs) +           # 可达
                W_V * visibility_cost(c, obs) +       # 可见/遮挡
                W_C * clearance_cost(c, obs) +        # 自碰撞/桌面
                W_B * balance_cost(c, obs) +          # 静态平衡裕度
                W_T * travel_time(self.c, c))         # 回标称正则

    def command(self, obs, progress):
        if self.safety.risk(obs):                     # 平衡/碰撞/人手/延迟
            self.c = self.c0                          # PR7：立即回标称
            return self.safety.clamp(self.c)
        if progress.stalled() and obs.t >= self.hold_until:
            cand = self.choose(obs, self.c)
            if cand is not None:
                self.c = cand
                self.hold_until = obs.t + HOLD_STEPS
        return self.safety.smooth(self.c)             # 限速/限幅/低通
```

### 5.2 RMC：模式发现、条件化与空抓后重配置

```python
# m = (arm, grasp_frame, approach_dir, grasp_height, support_hand, torso_assist)
MODES = discover_modes(DEMOS)        # 聚类 + VLM 命名 + 人工抽检 5%

class ReconfigurablePolicy:          # 仍是同一个 PolicyService / 同一个动作模型
    def reset(self, obs):
        self.failed = set()
        self.m = self.select(obs, exclude=self.failed)

    def select(self, obs, exclude):
        scores = {m: prior_success(m, obs.task) * affordance(m, obs)
                  for m in MODES if m not in exclude}
        if not scores:
            return MODE_DEFAULT
        m = max(scores, key=scores.get)
        return m if scores[m] > TAU_MODE else MODE_DEFAULT

    def get_action(self, obs):
        if empty_grasp_detected(obs):                 # 夹爪闭合 + 物体未动 + EE 位移小
            self.failed.add(self.m)
            self.rewind_to_last_verified_knot()       # 回退到最近验证节点，不整段重放
            self.m = self.select(obs, exclude=self.failed)
        return self.vla.propose_chunk(obs, mode=self.m)  # 语言后缀或 embedding 注入
```

| height std ≥0.01 | 12/32 任务 | 高度存在帧级变化，不是常数 |
| hmin <0.70 | 22/32 任务 | 任务会降低基座以够低处 |
| max\|vx,vy\| >0.1 | 7/32 任务 | 少数任务确实需要基座平移 |
| p4 mean 范围 | 0.113–0.214 | 任务级躯干先验不同，不能全局常数 |
| p3 非零 | 1/32 任务 | 腰部 yaw 仅在 OrganizeTools 明显 |
| 空抓周期 | 62/180（34.4%，启发式） | 成功轨迹内含空抓/重抓，I5/I11 有真实信号 |

**注意**：height span 是任务级 min/max，不代表每个 episode 都大幅移动；空抓是启发式，需人工抽检 5% 后再用于训练。结论只用于「方向性支持 AWN/RMC 值得做」，不用于估计真机增益。

### 6.2 先导机制检查（workspace 内合成实验，非基准证据）

来自 `exp/r28_reconfig_results.json` 的合成检查（reconfigurable mechanism × instance segmentation × action chunking）：

| 替代绑定检索 top-1 | full（语义+affordance+尺寸+位置+可达）0.978；sem_only 0.254；sem_aff 0.359 | 模式/替代选择必须带几何与可达性，纯语义不够 |

### 6.3 分级消融协议

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0 | AWN：固定构型 vs height-only vs height+waist vs full 的 `Δreach/Δvis/Δstability/Δtime`；RMC：模式纯度、模式可预测性、空抓后重配置的离线期望收益；I5：真实恢复段 vs 合成段的质量 | 离线（免费） | AWN：存在任务族 `Δreach>0` 且 `Δstability` 不降；RMC：模式纯度 ≥0.8、重配置离线收益 >0；I5：真实段占比 ≥30% 则优先真实段 |
| L1 | 模式条件化 LoRA vs baseline；AWN 与 RMC 的 2×2 析因；安全 shield 开/关 | 1×24GB + 少量真机 | 主效应显著且无标称任务退步；AWN/RMC 至少一个任务族 ≥5pp |
| L2 | L0+L1 联合 top 2–3 组合；每任务 ≥2 次 × 2–3 任务 | 单任务通道 | 真机增益 ≥ 离线预测的 50%；无安全事故；p99 不恶化 |
| 门禁 | PR4：run_client 全流程 + p99 + 动作健康度；PR6：pivot 探针报告 | 本地 stub + 探针 | 0 拒绝动作、p99<40ms、探针语义确认 |

### 6.4 功效分析（决定 L2 预算）

- 320 个计分 trial；任务级 10 次 → 成功率分辨率 10%。
- 每轴每任务 2 次 → 轴级 64 trial；`SE ≈ sqrt(0.3×0.7/64) ≈ 5.7pp`。
- 因此：L2 只测**预期 ≥5pp** 的机制；用跨任务配对/分层分析；不要用 1–2 个任务的差异做模型选择；AWN/RMC 的早期判断以 L0 的连续代理为主，真机只做确认。

### 6.5 首批 L2 排队计划

1. **pivot 探针**（不是 A/B，是安全前提）：确认语义/限位/方向。
2. **AWN height-only**：在 PickOutBatteries / PaperCupStacking / OrganizeTools 上对比 static。
3. **RMC 模式条件化**：ZipUp / PlugCharger / PourOutMedicine 三个弱任务 + 2 个对照。
4. **RMC 空抓重配置**：只在 L0 显示恢复收益 >0 的任务上开。
5. **AWN × RMC 2×2**：只测 L0/L1 联合排名 top 组合。
