# 第 13 轮 · SENTINEL：在 VLA 外面加一层「无学习权重的合规安全仲裁层」

> 检索/复核日期：**2026-11-02（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新一轮灵感循环第 1 轮，三个词是「伦理与合规」「安全交互」「多机器人协作」。本轮**不推倒**第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO；而是把 CHUNK-SERVO 的「30 步规划 + 5 步伺服」包进一层可审计、可解释、零学习权重的安全/合规外壳。

## 0. 先给结论：头部缺的不是更大的 VLA，而是「在最后一厘米、在人伸手进来时、在 N 台机器人同时跑时，敢于说不」的运行时层

截至 2026-11-02，官网首页/榜单仍是同样的 8 个模型、同样的分数：MolmoAct 29.7%、WALLOSS 28.5%、DreamZero 27.9%、spirit 25.9%、DM 23.5%、PI 22.8%、GigaBrain 22.6%、gr00t 20.5%。`runs.html` 现在列出 256 条「模型 × 任务」记录（8×32），但详情页仍明确写着「测试视频占位，后续可替换为真实视频文件」；成功率仍出现 21.5%、19.9%、27.2% 这类**不是 10 次 trial 整数倍**的数。结论不变：**29.7% 是赛事方的预览上限/难度信号，不是可复现的 SOTA，也不能当失败分布。**

真正没有被头部方案系统解决的，是三个「不冒烟但漏分」的缺口：

1. **人为干扰轴占 20%**：每个任务 10 次里 2 次是人为干扰；官方手册明确其形式是「任务执行过程中临时改变物品位置」等。多数 VLA 在成功演示上训练，没见过「人把物体拿走/移动」的负样本；它们会继续执行旧计划、追着物体跑，甚至在人手进入工作区时继续运动。
2. **步骤分是 tie-break**：排名先看 32 任务平均成功率，相同看平均步骤分。一次「失败但完成了 70% 步骤」和一次「失败且撞翻一切」在成功率上一样，在步骤分上不同。当前 VLA 没有「安全止损/保住部分分」的机制。
3. **N 台机器人并行评测**：官方要求从 8765 起暴露 N 个连续端口；允许共享一个模型，但 README 明确警告 **并发** 与 **每端口状态隔离**。多数队伍要么 N 份模型（显存爆炸），要么共享后端但队列/状态处理不干净；一个端口卡住会拖垮其他端口，延迟抖动还会被计入「结果可信度」。

所以本轮的押注是 **SENTINEL**：

> **不训练第二个模型，不碰单模型红线；在 VLA 与 API 之间放一个确定性仲裁层：该停就停、该让就让、该让另一只手就换手、该让另一个端口就先服务它。它不提高模型的上限，但把下限、步骤分和合规风险变成可管理的工程变量。**

SENTINEL 由五个模块组成，恰好对应三个灵感词：

| 模块 | 全称 | 一句话 | 对应灵感词 |
|---|---|---|---|
| **SHIELD** | Safety & Kinematic Guard | 确定性动作护栏：限位、限速、自碰撞、桌面、人体距离、平滑、NaN、看门狗；危险时停/退/放 | 安全交互、伦理与合规 |
| **YIELD** | Human-Aware Yield & Resume | 检测「不是我的动作造成的场景变化」；人动物体就等，人伸手就退，稳定后重定位再恢复 | 安全交互 |
| **DUET** | Dual-Arm Arbitration | 单 VLA 出双臂，仲裁器做角色分配、臂-臂冲突、遮挡与换手 | 多机器人协作（同一台 G1 的双臂） |
| **FLEET** | Fleet Governance | N 端口隔离、共享 VLA 的 deadline-aware 批处理、跨机器人标定注册表、只读案例库 | 多机器人协作（N 台并行） |
| **LEDGER** | Compliance Ledger | 模型哈希、模块清单（学习/非学习）、每端口状态、干预原因、延迟/动作统计；可审计 | 伦理与合规 |

**最值得押注的单点**：不是 DUET，也不是 FLEET，而是 **YIELD + SHIELD 的组合**。理由很直接：人为干扰轴是 20% 的固定权重；这一步不需要新数据、不需要新模型、不需要 6B 以上算力，只需要一个确定性的「检测—让行—等待—重定位—恢复」状态机，以及一个「默认放行、只在风险高时否决」的护栏。它是当前投入产出比最高的边际改进。

- 但 `details.html?model=MolmoAct2&user=DexHacker&task=Pack%20Phone` 仍明确显示「测试视频占位，后续可替换为真实视频文件 / Placeholder video」。来源：<https://unibot.unitree.com/details.html?model=MolmoAct2&user=DexHacker&task=Pack%20Phone>（检索 2026-11-02）。
- 21.5%、19.9% 等仍不是 10 次 trial 的整数倍（真实 10 次只能是 0/10、1/10、…、10/10）。**判断不变：这是聚合/预览数据，不能反推单 trial 失败原因，也不能当任务难度表。**

### 1.2 官方手册：人为干扰是「移动物品」，不是「和人打架」

中文参赛手册（`r.jina.ai` 抓取，检索 2026-11-02）明确：

- 32 个任务，每个任务 10 次独立运行；10 次包含 5 类泛化，每类 2 次：位置、干扰物、桌面背景、未见物品、**人为干扰**。
- 人为干扰泛化的描述是：「在任务执行过程中加入人为干扰因素（如临时改变物品位置等），考察模型的鲁棒性与抗干扰能力。」
- 单次真机执行上限 **180 s**，超时记失败，并按执行情况计算步骤分。
- 排名：32 任务总平均成功率；相同看总平均步骤分；再相同看更早提交。
- 所有任务须基于**同一模型**，不得混合多个模型；模型类型不限。
- 另有**不计分的单任务测试通道**。

来源：<https://r.jina.ai/https://scnhkkqlu12w.feishu.cn/docx/Uz7OdFBcDoqP1dxgH62cHW1CnMh>、<https://r.jina.ai/https://scnhkkqlu12w.feishu.cn/docx/ZNHIdaGx0oPOlBxNVxkcswqqnnh>（检索 2026-11-02；飞书文档在 jina 下只稳定拿到第 1–2 章，后续以官方页面为准）。

**对方案的约束**：

- 「安全交互」的重点不是「人机物理协作」，而是 **(a) 人手进入工作区时不要撞人；(b) 人移动物体时不要追着旧目标跑；(c) 人拿走物体时不要抢；(d) 人把物体放回后能恢复**。
- 不需要训练「人类意图识别」大模型；用「场景变化残差 + 光流 + 目标位姿变化」的确定性检测即可。
- 不要声称「多机器人协同完成同一任务」——赛制是 N 台机器人**并行独立**评测，没有跨机器人观测/动作接口。

### 1.3 提交 README：N 端口、共享模型、并发与状态隔离

提交模板 README（检索 2026-11-02，<https://raw.githubusercontent.com/unitreerobotics/unibot_submission/main/README.md>）明确：

- 评测跨 **N 台测试机器人**，随机顺序；评测端每台机器人连接一个固定端口；提交必须从 **8765** 起暴露 **N 个连续端口**，端口数必须精确等于 N。
- 每个端口必须独立、可靠地完成该机器人的整个交互流程。
- 两种常见实现：
  - **Approach 1**：每个端口一个独立进程，各加载一份模型；隔离最简单，但 N 份显存/内存。
  - **Approach 2**：多个端口共享一个模型；需要自己做请求分发。README 明确警告两点：**并发**（不同端口可能同时调用，共享后端不能互相阻塞、不能抬高延迟）和**状态隔离**（每个端口对应不同机器人上的不同 episode，`reset` 与历史状态必须互相隔离，绝不能共享）。
- 评测端逐步记录每次 `get_action` 的延迟、波动和返回动作的统计规律，作为**结果可信度**的一部分；建议保持每步推理延迟稳定、动作格式良好、避免异常离群。

**对方案的约束**：

- SENTINEL 必须每端口一个轻量 `GuardService`，独立状态机、独立 reset、独立日志；共享的只有只读目标库/标定先验/VLA 权重。
- 护栏/让行/仲裁的计算必须在 CPU 上毫秒级完成，不能抢 GPU、不能把 p99 拉高。
- 干预动作必须**平滑**（限幅、混合 2–3 步），否则会被动作统计视为异常，反而损害可信度。

### 1.5 近期工作：安全层、人因、双臂、舰队都有新证据，但没人把它们合起来

以下均为 arXiv 2026-10 预印本（检索 2026-11-02），**未复现**，只作为设计证据（B 级）：

| 工作 | 关键结论 | 对本轮的意义 |
|---|---|---|
| **VLA-Stem**（arXiv 2610.37378） | 不微调底层 VLA，把 action chunk 转成运动参考，用 RL 的 Stem policy 在推理时修改执行；6 个受限仿真设置平均无碰撞任务成功 52.8%，最强安全基线 23.7% | 证明「VLA 外面加安全层」有效；但它是**第二个学习策略**，在 UniBot 单模型规则下有合规风险。SENTINEL 反其道：零学习权重 |
| **When Human Corrections Travel**（arXiv 2610.32888，CoRL 2026 SPAIS） | 核心论点（无实验）：联邦 VLA 适配中，共享更新可能提升平均成功率却压制罕见安全干预；强调保留修正的上下文/不确定性、在接收机器人闭环里验证、评估泄漏 | 直接支撑「人因安全不能只靠平均成功率」；也警告「跨机器人共享学习更新」的合规/安全风险。SENTINEL 只共享只读标定/案例，不共享权重 |
| **EAST**（arXiv 2610.34358） | 数字孪生故障注入，把安全证据转成可执行测试；6 个 RoboTwin 任务、ACT/RDT 两种策略；82 次有效执行在**完成任务的同时违反了安全要求** | 说明「成功率 ≠ 安全」；给 SENTINEL 一个仿真压测方法：不只测成功，还测碰撞/越界/人距 |
| **World Dreamer v5-lite**（arXiv 2610.37518） | 多机器人 world-action model：共享世界状态、每机器人一个 query、动作流分离；RoboFactory 74.0%，真实 4 任务 78.8% | 「多机器人」在模型层已有探索；但 UniBot 的 N 台是并行评测，不需要共享世界状态。可作为「不要做」的边界 |
| **Networked Humanoid Intelligence**（arXiv 2610.34740） | 综述：人形机器人从单机走向联网舰队；通信、协调、协作、社会交互四个功能；指出 stale information、unsafe knowledge propagation 等风险 | 给 FLEET 的术语和风险清单；强调「 accountable human oversight」 |
| **Not an Accident**（arXiv 2610.31923） | 安全滤波器的保证只在参数配置正确时成立；错误配置可被正常用户交互利用（goal insertion）；SIREN 自动找漏洞 | 警告：护栏参数必须按任务/环境配置并审计；不能把「有护栏」当「绝对安全」 |
| **Which Hand Was Late?**（arXiv 2610.37533） | 双臂工具使用的失败诊断：工具滑脱、两只手时序错、双重原因；单手腕部传感只能读自己；VLM 内部状态含「哪只手晚了」但答案不一定报告 | 支撑 DUET 的「角色/时序」诊断；也说明双臂失败不能只看单臂 |
| **Learning Functional Specialisation**（arXiv 2610.33947） | 差分目标 + 固定手-任务分配的功能特化最强，双臂成功 81.33%；角色反转在强特化下掉 80.46pp | 支撑 DUET 的「固定角色 + 阶段化分配」；但这是仿真 musculo-skeletal，不是 G1，需谨慎 |
| **Active Reachability Learning**（arXiv 2610.33317） | 在 29-DoF Unitree G1 上做运行时可恢复性监控，主动探索 recoverability envelope，避免 OOD 乐观幻觉 | 支撑「运行时监控 + fallback」在 G1 上可行；SENTINEL 的 SHIELD 可以借鉴其「不确定就判不可恢复」的保守原则 |
| **Keeping Contact**（arXiv 2610.36961） | 双臂非抓取操作的任务自适应摩擦裕度，用 SOCP 求接触力 | 接触安全的好思路，但 UniBot API **没有力/触觉**，不能直接部署；只能用于离线分析/阈值设计 |

**判断**：安全层（VLA-Stem）、人因（Human Corrections Travel）、双臂诊断（Which Hand Was Late）、舰队（Networked Humanoid Intelligence）分别都有工作，但**没有人把它们做成「单模型合规 + 零学习权重 + 竞赛步骤分 + N 端口」的组合**。这就是 SENTINEL 的空位。

### 1.6 头部方案的做法与瓶颈：为什么本轮不卷更大的模型

榜单名字对应真实的公开模型家族（分数是预览，但路线是真实的）：

| 模型家族 | 公开路线 | 优势 | 与本轮相关的瓶颈 |
|---|---|---|---|
| **MolmoAct2** | action reasoning model；Molmo 2-ER + action expert + adaptive depth reasoning；强调 3D 空间推理、推理加速、无 per-task 微调 | 3D/空间语义强；双臂 | 仍是开环 chunk；最后插入/挂/拉链的接触精度；人因恢复 |
| **WALL-OSS-0.5** | 4B VLA（3B VLM + action expert）；公开材料称 15 个真机任务 60.5% average task progress | 预训练可用；progress 高 | progress ≠ success；最后一步失败就 0 分；实时性 |
| **DreamZero** | 14B Wan2.1 video-diffusion world-action model；预测未来视频再出动作 | 长程预测/规划 | 14B 推理重；世界模型不直接解决毫米级接触；长 chunk 更不反应 |
| **π0.5** | 开放世界泛化 VLA | 语义/新场景泛化 | 接触密集任务精度；远程延迟 |
| **GigaBrain-0** | 世界模型生成数据 + VLA | 数据效率/泛化 | 生成数据物理保真度；最后 3 厘米 |
| **GR00T N1.5** | NVIDIA 通用人形 VLA | 生态/embodiment | 任务特定精度；数据覆盖 |

共同点：**都是 action chunk 开环执行；模型越大，chunk 越长，越不反应；世界模型解决「想象未来」，不解决「现在偏了 2mm」；没有一个是「接触/人因闭环」模型。**

四个可能的创新维度，本轮的取舍：

| 维度 | 可能做法 | 边际收益/成本 | 本轮取舍 |
|---|---|---|---|
| **数据** | 33k 演示 + 恢复片段 + 仿真故障注入；微调同一 VLA | 中/中；可能 +1–3pp；有遗忘风险 | **P2 可选**（SAFE-CURRICULUM）；不作为头号 |
| **模型架构** | 更大 VLA / World Model / 混合；共享世界状态 | 低/高；官方 WLA 6B 已把「大模型」做完；越大越慢 | **不做**；只做 action-head 微调（若需要） |
| **训练策略** | 相位化 BC、角色 token、恢复数据、RL 安全层 | 中/中高；VLA-Stem 证明有效但引入第二个学习策略 | **不做第二个学习策略**；只做同模型微调 |
| **接口/运行时** | 5 步 chunk、视觉伺服、安全护栏、YIELD、N 端口治理 | **高/低**；不改模型、不增数据、直接吃 20% human 轴和 tie-break | **主投**（SENTINEL） |

**结论**：不是「更大的模型」不重要，而是它的边际收益已经被官方 WLA 6B 和头部方案吃掉；当前 <30% 的共同瓶颈在**执行层的接触精度、人因恢复、N 端口可靠性**。这三件事都可以用零学习权重的运行时层改善，且不触碰单模型红线。**这就是本轮把「伦理/安全/多机器人」三个词落到接口工程而不是模型架构的原因。**

## 2. 三个灵感词在 UniBot 里的真实落点

先把「词」翻译成「赛制表面」，否则容易写成泛泛的伦理讨论：

| 灵感词 | UniBot 里的真实表面 | 该做什么 | 不该做什么 |
|---|---|---|---|
| **伦理与合规** | ① 单模型规则（不得混多个模型）；② 结果可信度（延迟/动作统计）；③ 人机安全；④ 数据隐私 | **LEDGER**：模型/模块/端口/干预全记录；**SHIELD**：零学习权重的安全否决；提交材料写清「唯一学习模型 + 确定性控制器」 | 不加第二个学习的安全分类器/人类检测器/残差策略；不利用榜单预览/评测漏洞；不识别或记录人脸/身份 |
| **安全交互** | 人为干扰轴 2/10 = **20%**；人手可能进入工作区；人物体被移动/拿走 | **YIELD**：检测「非我所致」的场景变化；人动物体就等稳定；人伸手就退；人拿走就松手；稳定后重定位恢复 | 不追着人手里的物体跑；不在人手附近高速运动；不做力量对抗（没有力/触觉）；不声称「绝对安全」 |
| **多机器人协作** | ① 同一台 G1 的**双臂**协作；② N 台机器人**并行**评测、共享模型/端口 | **DUET**：双臂角色分配、臂-臂冲突、遮挡、换手；**FLEET**：N 端口隔离、deadline-aware 批处理、跨机器人标定注册表、只读案例库 | 不做「多台 G1 协同完成同一任务」（没有跨机器人观测/动作接口）；不在端口间共享 episode 状态；不做在线共享权重 |

一句话：**「多机器人协作」在 UniBot 里不是「多台机器人一起搬桌子」，而是「一台机器人内部两只手别打架 + N 台机器人并行时别互相拖垮」。** 这个区分是本轮最重要的战略判断。

## 3. 诊断：三个「不冒烟但漏分」的缺口

把一次失败拆开看，VLA 的输出是 action chunk，CHUNK-SERVO 让它每 5 步闭环一次；但仍然缺一个**有否决权的运行时层**：

```text
观测 → VLA 30 步 plan → CHUNK-SERVO 5 步伺服 → API 执行
                                      ↑
                          这里没有「停/让/换手/降速」的权限
```

### 3.1 缺口一：人为干扰轴没有「让行」语义

- 训练数据是成功演示，没有「人把物体移走」的负样本；模型会继续执行旧计划。
- 即使 GEO-RESIDUAL 检测到「场景变了」，CHUNK-SERVO 的反应是「重定位 + 重规划」，仍然可能**追着人手里的物体**或**在人手附近继续运动**。
- 正确行为是：**先让行，等场景稳定，再恢复**；如果人拿走了物体，应该松手/等待，而不是抢。
- 权重：20%。这是单一最大的、可被确定性逻辑吃掉的固定权重。

### 3.2 缺口二：步骤分没有「安全止损」

- 排名 tie-break 看平均步骤分；一次失败如果保留了已完成步骤，仍可能赢 tie-break。
- 当前 VLA 在不确定时会继续执行，可能撞翻已完成的物体、把已放入的物品打翻，导致步骤分倒退。
- 需要 **step-score-preserving fallback**：风险高时退到安全位、把手中物体放到最近的稳定位置、停止而不是乱动；宁可少做一步，不要毁掉已得分。

### 3.3 缺口三：N 端口没有「舰队治理」

- README 明确警告并发与状态隔离；这是很多队伍会踩的工程坑。
- 一个端口在接触段需要低延迟，另一个端口在远距离接近；如果共享后端用朴素 FIFO，接触段请求会被远距离请求堵住。
- 不同机器人的相机安装/光照/夹爪 TCP 有差异；单模型在 N 台机器人上的方差可能大于模型本身带来的差异。
- 需要 **deadline-aware 调度 + 每端口隔离 + 跨机器人标定先验**；这不是模型创新，但它是「不丢分」的创新。

### 3.4 共同原因

三个缺口都指向同一个结构问题：**VLA 是「提议者」，不是「决策者」**。它输出动作，但没有权限说「不」。SENTINEL 就是把「否决/让行/仲裁/治理」这四种权限，用一个零学习权重的层补上。

## 4. SENTINEL 架构：五个模块，一个原则

**原则：默认放行，只在风险高时干预；干预必须平滑、可解释、可审计。**

```text
                    ┌──────────────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1)          │
                    └───────────────┬──────────────────────────────┘
                                    │ websocket: obs / action chunk
                                    ▼
        ┌───────────────────────────────────────────────────────────┐
        │  Per-port GuardService (CPU, <5ms typical)                │
        │                                                           │
        │  obs ──▶ LEDGER (log)                                     │
        │        ──▶ YIELD (detect / yield / wait / resume)         │
        │        ──▶ DUET  (dual-arm role / collision / handover)   │
        │        ──▶ SHIELD (kinematic / human / smooth / watchdog) │
        │        ──▶ chunk selector (optional RC-BoN)               │
        │                                                           │
        │  state: per-port, reset-isolated, no cross-port sharing   │
        └───────────────┬───────────────────────────────────────────┘
                        │ async, batched, deadline-aware
                        ▼
        ┌───────────────────────────────────────────────────────────┐
        │  Shared VLA server (GPU)                                  │
        │  UnifoLM-WLA-1.0 / VLA-0, 30-step plan                    │
        └───────────────────────────────────────────────────────────┘

        Read-only shared assets (never episode state):
        ├─ demo goal/keyframe index (33k episodes)
        ├─ calibration registry (per-robot photometric/geometric prior)
        └─ case memory (failure signature → recovery primitive)
```

### 4.1 SHIELD：确定性动作护栏

**输入**：当前 obs（四路 RGB、双臂关节、EE 位姿、夹爪、下身体、语言）、VLA 的 5 步 chunk、G1 URDF、标定注册表。
**输出**：放行 / 限速 / 限幅 / 延迟 / 保持 / 后退 / 松手 / 安全停。

检查项（全部确定性，无学习权重）：

1. **关节/速度/加速度**：`q ∈ [q_min,q_max]`，`|qdot| ≤ qdot_max`，`|qddot| ≤ qddot_max`；用有限差分从 `left_arm[7]`、`right_arm[7]`、`lower_body[15]` 估计。
2. **工作空间/桌面**：EE 不低于桌面安全高度；不越过身体中线/肩部高度；不进入头部相机架。
3. **自碰撞**：双臂/躯干用胶囊体近似，臂-臂、臂-躯干最小距离 ≥ `d_min`；预测 5 步内的最小距离。
4. **人体距离**：从头部双目/残差估计人手/人体区域；若 `d_human < d_safe` 或预测碰撞时间 `τ_tc < τ_stop`，触发 YIELD。
5. **夹爪/滑移**：夹爪开度突变 + GEO-RESIDUAL 的 `r_grasp` 突变 → 滑移；降低切向速度/加大夹持/重抓。
6. **动作合法性**：NaN/Inf、形状、token、时间轴；任何异常 → 返回上一组合法 chunk 或安全保持。
7. **平滑性**：`||a_t - a_{t-1}||` 限幅；干预动作与 VLA 动作**混合 2–3 步**，避免动作统计被判定为异常。
8. **看门狗**：VLA 超时/端口卡住 → 用旧 plan + SHIELD 保持；绝不阻塞 `get_action`。

**Step-score-preserving fallback**：当风险高且任务明显不可恢复时，不退化成「乱动」，而是：

- 未夹持：退到最近的安全位（桌面以上、身体前方、无碰撞）。
- 已夹持：把物体放到最近的稳定位置（桌面空位/已得分区域），再停。
- 记录「为什么停」到 LEDGER；不假装成功。

### 4.2 YIELD：人因让行与恢复

**检测**（不用人类检测模型）：

- **场景变化残差**：GEO-RESIDUAL 的 `edit_score`（机器人动作解释不了的 3D 残差）。
- **光流/变化区域**：头部双目/腕部图的稠密光流，找「与机器人运动不一致」的 blob。
- **目标位姿变化**：受器/目标物体位姿相对上一帧的跳变。
- **分类**：blob 靠近目标/桌面 + 运动连贯 → 人移动物体；blob 靠近 EE + 大面积 → 人手进入工作区；全局亮度/纹理变化 → 背景/光照（不触发让行）。

**状态机**：

```text
NORMAL ──edit_score > θ_e 连续 K 帧──▶ DETECT
DETECT ──人手在安全距离内──▶ YIELD（后退/停/松手）
DETECT ──物体被移动──▶ WAIT（等场景稳定）
WAIT ──连续 M 帧残差低──▶ RELOCALIZE（重估目标位姿）
RELOCALIZE ──目标可见/可达──▶ RESUME（保守增益）
RELOCALIZE ──目标消失/不可达──▶ REPLAN（VLA 重规划）
任意 ──等待 > T_wait 或重试 > N_max──▶ SAFE_PARK（保步骤分）
```

**行为规则**：

- 人伸手：沿接近轴后退 2–5 cm，降速到 30%，松开未夹持的手；已夹持则保持并等待。
- 人移动物体：**不要追**；等物体稳定（连续 M 帧低残差）再重定位。
- 人拿走物体：松手，等待；不要抢。
- 恢复：用 CHUNK-SERVO 的相对目标（`T_target_ee*`）重新对准；增益降档，避免超调。
- **可读性**：在人附近限速、避免突然转向、保持 EE 低于肩高、动作方向可预测。

### 4.3 DUET：双臂仲裁

单 VLA 输出双臂；DUET 只在**预测到冲突**时介入，否则直通。

- **角色分配**：按任务阶段给两只手分配「稳定/操作/辅助」；用 2×2 代价矩阵 + Hungarian：
  `C_ij = α·距离 + β·遮挡 + γ·碰撞风险 + δ·阶段先验`。
- **臂-臂冲突**：预测 5 步内胶囊距离 < `d_min` → 低优先级臂延迟 2–5 步或降速；仍冲突 → 改角色。
- **遮挡**：一只腕部相机被另一只臂挡住 → 用头部双目补；调整臂的顺序/高度，不硬用被挡的腕部图。
- **换手**：一只手到达工作空间边缘/被遮挡/夹爪滑移 → 把物体交给另一只手；换手位姿从演示检索。
- **失败诊断**：借鉴 arXiv 2610.37533，双臂失败要区分「工具滑脱」「哪只手晚了」「双重原因」；DUET 记录每只手的时序，触发「重试/换手/降速」而不是盲目重规划。

### 4.4 FLEET：N 端口治理

- **每端口一个 GuardService**：独立状态机、独立 `reset()`、独立日志；共享的只有只读资产。
- **共享 VLA server**：请求带 deadline（`D = H_c/f_c`）和阶段标签（接近/接触/恢复）；调度器优先接触段、合并同 deadline 请求、动态批大小；保证 p99。
- **降级**：VLA 超时 → 旧 plan + SHIELD 保持；连续超时 → 该端口进入 safe park，不拖累其他端口。
- **标定注册表**：每台机器人的光度（增益/偏置）和几何（相机外参/夹爪 TCP）残差；用首批帧 + 桌面平面/机器人位姿做确定性最小二乘；跨机器人共享**先验**，不共享 episode 数据。
- **只读案例库**：把 33k 演示中的「恢复/换手/重试」片段做成索引；端口按任务/阶段检索；不写入、不共享在线状态。
- **审计**：每端口事件日志；证明隔离、可复现、无跨端口泄漏。

### 4.5 LEDGER：合规账本

记录：

- 模型名、checkpoint 哈希、参数量、唯一学习模型声明。
- 模块清单：哪些有学习权重（只有 VLA），哪些是确定性（SHIELD/YIELD/DUET/FLEET 的几何/控制部分）。
- 每端口：episode id、reset 时间、状态转移、干预类型/原因、延迟。
- 动作统计：p50/p95/p99、离群点、NaN、限幅次数。
- 数据/隐私：只使用官方数据；不记录人脸/身份；不把人类视频用于识别。

用途：提交材料、争议时自证、复盘、满足「结果可信度」的透明性要求。

## 5. 创新点清单（本轮维护）

> 评分维度：动机（为什么现在做）、差异（和现有方案/头部方案比）、可行性（数据/算力/接口）、资源、落地步骤、风险。等级：A=官方事实可核实，B=公开预印本/我们分析，C=设计假设待验证。

| **技术可行性** | 中高。2×2 角色分配 + 胶囊碰撞 + 延迟执行可实现；换手需要演示检索位姿。 |

### I4 · FLEET：N 端口治理 + 跨机器人标定

| 项 | 内容 |
|---|---|
| **动机** | 官方要求 N 个连续端口、每端口独立；README 明确警告并发与状态隔离；跨机器人相机/夹爪差异会放大方差。 |
| **与现有方案差异** | 多数队伍只做「N 份模型」或「朴素共享」；FLEET 做 deadline-aware 批处理、每端口隔离、跨机器人标定先验、只读案例库。 |
| **技术可行性** | 高。Python 多进程/异步 + 共享内存/队列即可；标定用经典最小二乘；无需新模型。 |
| **所需资源** | 1 名后端/系统工程师；N 台机器人或仿真多端口；压测脚本。 |
| **落地步骤** | ① 每端口进程 + 独立状态；② 请求队列/批处理；③ p99 压测；④ 标定注册表；⑤ 故障注入（超时/断连）；⑥ 全量干跑。 |
| **风险** | 共享后端成为瓶颈；状态泄漏；调度不公平。缓解：deadline 优先、批大小自适应、每端口 watchdog、隔离测试。 |

### I5 · LEDGER：合规审计与单模型自证

| 项 | 内容 |
|---|---|
| **动机** | 单模型规则 + 结果可信度；一旦被质疑「你加了第二个模型」，申诉成本极高；透明日志也能帮助复盘。 |
| **与现有方案差异** | 多数队伍不会准备模块级审计；LEDGER 把「学习/非学习」边界、端口隔离、干预原因写成可验证记录。 |
| **技术可行性** | 高。结构化日志 + 哈希 + 报告生成；几乎零算力。 |
| **所需资源** | 0.2 人；无需额外数据/GPU。 |
| **落地步骤** | ① 定义 schema；② 在 GuardService 埋点；③ 生成提交报告；④ 与官方沟通口径（若需要）。 |
| **风险** | 日志过多影响延迟；口径不被认可。缓解：异步落盘、采样、只记录关键事件；提前邮件确认。 |

### I6（可选）· RC-BoN：同模型的风险约束 best-of-N

| 项 | 内容 |
|---|---|
| **动机** | 扩散/流 action head 可采样多个 chunk；在接触前/人因场景，用测试时算力换安全性。 |
| **与现有方案差异** | 不新增模型；只对同一 checkpoint 采样 K 次，用确定性风险 + 进度评分选一个；只在关键阶段开，控制延迟。 |
| **技术可行性** | 中。取决于 action head 是否可采样、K 次前向的延迟；K=2–4 可能可接受，K=8 可能超时。 |
| **所需资源** | GPU 推理余量；风险评分器；离线回放。 |
| **落地步骤** | ① 确认 WLA 是否支持多噪声采样；② 离线评估 K/延迟/收益；③ 只在预接触/人因阶段开；④ A/B。 |
| **风险** | 延迟 p99 超标；评分器与真实安全不一致；收益不稳定。缓解：阶段门控、K≤4、延迟预算硬约束、失败回退 K=1。 |

### I7（可选）· SAFE-CURRICULUM：从演示中挖恢复片段，微调同一 VLA

| 项 | 内容 |
|---|---|
| **动机** | 成功演示里也有「接近失败→后退→重抓」的片段；用它们微调同一模型，可让 VLA 自身学会恢复，而不是全靠外部规则。 |
| **与现有方案差异** | 不是收集新数据/训新模型；是对官方 WLA 的 action head 做同模型微调，数据来自 33k 演示的恢复片段 + 仿真扰动。 |
| **技术可行性** | 中。需要恢复片段自动挖掘/标注；微调成本 24GB GPU 可承受；但可能破坏原任务能力。 |
| **所需资源** | 1–2 GPU 周；数据挖掘脚本；单任务通道。 |
| **落地步骤** | ① 定义恢复片段（滑移/重抓/后退）；② 自动挖掘 + 人工抽检；③ 同模型 LoRA/action-head 微调；④ 回归测试（FoldTowel 等）。 |
| **风险** | 灾难性遗忘；恢复片段噪声；单模型合规没问题但收益不确定。缓解：小学习率、LoRA、保留 base 回滚、严格回归。 |

**本轮剪枝**：

- 不做第二个学习的安全分类器/人类检测器/残差策略（单模型风险 + 延迟）。
- 不做多台 G1 协同完成同一任务（没有接口，赛制也不是这个）。
- 不做力/触觉闭环（API 没有）。
- 不做 30Hz 的 CBF-QP/全身优化（延迟 + 无深度/力）。
- 不做「用人类视频训练意图识别」（隐私 + 数据 + 第二个模型）。
- 不把预览榜单当实测难度表（已证伪）。
- 不做「在线共享权重」的联邦学习（合规 + 非平稳 + 安全传播风险，见 arXiv 2610.32888）。

## 6. 与第 10/11/12 轮的关系：保留、升级、剪枝

**保留**：

- FACT-VLA 的相位化 BC、CAC 柔顺执行、EGP 证据门控。
- GEO-RESIDUAL 的动作条件化残差、米制表面距离、编辑检测（本轮直接作为 YIELD 的检测器）。
- CHUNK-SERVO 的 30 步规划 + 5 步执行、演示检索相对目标、数字孪生标定 RTT/增益。
- 官方 WLA 基座、33k 演示、单任务通道、合规三模式 C1/C2/C3。

**升级**：

- 从「检测到编辑 → 重定位」升级为「检测 → 让行 → 等待稳定 → 重定位 → 恢复」。
- 从「动作后处理」升级为「动作前否决 + 动作中仲裁 + 动作后审计」。
- 从「单机器人执行」升级为「每端口 GuardService + 共享 VLA + 标定注册表」。
- 从「成功率」升级为「成功率 + 步骤分 + 安全违规 + p99」的多目标。

**剪枝**：

- 不再把「更大 VLA / 更长 chunk」当默认答案；CHUNK-SERVO 已说明执行层是瓶颈。
- 不再做「32 任务各训一个策略」；规则禁止且不泛化。
- 不再做「完整 sim-to-real 策略训练」；数字孪生只做风洞/故障注入。
- 不再做「第二个学习模型」；SENTINEL 全部确定性。

## 7. 竞赛策略：把 320 trials 当投资组合

### 7.1 算术（保守，不吹）

- 总分 `S = (1/32) Σ p_t`；人为干扰轴 `ΔS_human = 0.2 × Δp_h`。
- 若 YIELD 把 human 轴从 15% 提到 30%：`0.2 × 15pp = +3.0pp`。
- 若 DUET 让 10 个双臂任务各 +5pp：`10/32 × 5 = +1.6pp`。
- 若 FLEET 避免 5% 的超时/断连：约 `+1.0–1.6pp`。
- SHIELD 主要保步骤分（tie-break），不直接加成功率；按 +3–5% 步骤分估计。
- **合计保守 +3–6pp；乐观 +7–8pp。** 不要声称 +10pp；320 trials 的成功率标准误约 2.4pp，+1–2pp 不能当结论。

### 7.2 任务分档（先验，待单任务通道更新）

- **H 档（人因/接触优先，先做）**：HangCup、PlugInEthernet、DisconnectEthernet、Unlock、ZipUp、ArrangeTestTubes、StackBowls、PackPhone、OrganizePencilCase。
- **B 档（双臂优先）**：PackBag、ToolboxStorage、StorePaddle、StoreEarphones、PaperCupStacking、StoreCups、SyringeWaterTransfer。
- **V 档（VLA/语义优先）**：FruitSorting、ColorArrangement、OrganizeTools、FoldTowel、SpellRobot、ConveyorSorting。
- 优先级：`priority_t = (0.2×human_gain_t + bimanual_gain_t + step_gain_t) / cost_t`。

### 7.3 单任务通道协议

1. 选 5 个代表任务：PlugInEthernet（插入）、HangCup（挂）、ZipUp（拉链）、StackBowls（叠）、FoldTowel（变形，防回归）。
2. 每个任务 5 次 A/B：SENTINEL off / on；同一初始条件；记录成功、步骤分、耗时、p99、干预次数。
3. **人因专项**：在单任务通道里人为移动物体 2 次/任务，测 YIELD 的检测延迟/恢复率/误让行。
4. 通过：≥3/5 任务 +10pp（或 human 轴 +15pp），FoldTowel 不回归 >5pp；否则不烧正式提交。
5. 再扫 `H_c ∈ {3,5,8}`、`d_safe`、`T_wait`；选 p99 与成功率的折中。

### 7.4 提交节奏

- **W0**：官方 WLA + CHUNK-SERVO + SHIELD 基线；单任务跑通；LEDGER 埋点。
- **W1**：YIELD + 人因 A/B；若通过，提交安全基线（若允许多次）。
- **W2–W3**：DUET + 双臂 A/B；FLEET 压测。
- **W4**：RC-BoN（可选）+ 全量干跑。
- **W5**：最终提交；保留回滚开关。
- 若只允许一次提交：W4 后再交；不要用正式 320 trials 做未验证的 A/B。

## 8. 伦理与合规：不是附录，是设计约束

### 8.1 单模型合规

- SENTINEL 的 SHIELD/YIELD/DUET/FLEET 的几何/控制部分**零学习权重**；唯一学习模型是 VLA。
- 若需要视觉描述子，用**同一个 VLA checkpoint 的 encoder**（C3），不加载第二个模型。
- LEDGER 记录「学习/非学习」模块清单；提交材料主动说明。
- 不把「规则引擎」包装成模型，也不把「模型」藏在规则里。

### 8.2 人机安全

- 人靠近：降速、后退、保持最小距离、避免突然转向。
- 人拿走物体：松手、等待；不抢、不追。
- 人把物体放回：稳定后重定位、恢复；不假设人一定会放回。
- 不做「假装安全」：如果检测置信度低，选择保守（停/等），而不是赌。

### 8.3 数据与隐私

- 只用官方 33k 演示和仿真；不收集人脸/身份/生物特征。
- 若使用人类扰动视频做离线分析，先匿名化/裁剪，只保留手/物体区域。
- 不把人类修正数据上传到共享池；跨机器人只共享只读标定/案例。

### 8.4 评测诚信

- 不利用榜单预览/占位视频/评分脚本的漏洞；不伪造 run。
- 报告配对 A/B + bootstrap 置信区间；不 cherry-pick。
- 如果发现安全滤波器漏洞（参考 arXiv 2610.31923 的 SIREN），**先报告赛事方**，不利用。
- 不把「安全停」当成功率；诚实记录失败。

## 9. 一句话押注

**在所有人继续卷 VLA 本体时，最值得押注的是 SENTINEL 的 YIELD + SHIELD：用零学习权重的确定性让行/护栏，吃掉 20% 的人为干扰轴、步骤分 tie-break 和 N 端口可靠性——它不提高模型上限，但把最容易漏掉的下限变成分数。**

## 2. 问题形式化

### 2.1 评分与 human 轴

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

人为干扰 2/10：

```math
\Delta S_{\mathrm{human}} = \frac{2}{10}\,\Delta p_h = 0.2\,\Delta p_h.
```

若 `Δp_h = 15pp`，全局 `+3.0pp`。这是本轮最硬的算术。

### 2.2 风险约束的动作选择

同一 VLA checkpoint 采样 K 个 chunk（仅当 action head 支持多噪声采样）：

```math
a^\star = \arg\max_{a\in\mathcal A_K}
\left[\widehat{\mathrm{Prog}}(a) + \lambda_s \widehat{\mathrm{Step}}(a)\right]
\quad \text{s.t.}\quad R(a)\le \varepsilon.
```

风险评分：

```math
R(a)= w_c C_{\mathrm{coll}}(a)+w_h C_{\mathrm{human}}(a)+w_j C_{\mathrm{joint}}(a)+w_s C_{\mathrm{smooth}}(a).
```

各项用预测轨迹 `τ(a)` 计算：

```math
C_{\mathrm{coll}} = \max\!\left(0,\; d_{\min} - \min_{t} d_{\mathrm{arm\text{-}arm}}(t)\right),
```

```math
C_{\mathrm{human}} = \max\!\left(0,\; d_{\mathrm{safe}} - \min_t d_{\mathrm{human}}(t)\right)
+ \max\!\left(0,\; \tau_{\mathrm{stop}} - \min_t \tau_{\mathrm{tc}}(t)\right),
```

```math
C_{\mathrm{joint}} = \sum_t \mathbf 1\!\left[q_t\notin[q_{\min},q_{\max}]\ \text{or}\ |\dot q_t|>\dot q_{\max}\right],
```

```math
C_{\mathrm{smooth}} = \max\!\left(0,\; \|\Delta a_t\|-\delta_a\right).
```

无可行动作 → 安全保持/止损。`K=1` 时退化为 SHIELD 单路过滤。

### 2.3 人因干预作为切换系统

用 CUSUM 检测「非我所致」的变化：

```math
g_t = \max\!\left(0,\; g_{t-1} + e_t - \mu_0 - k\right),\qquad
\text{alarm if } g_t > h,
```

其中 `e_t` 是 GEO-RESIDUAL 的 `edit_score`（机器人动作解释不了的 3D 残差），`μ_0` 是正常残差均值，`k` 是容忍量，`h` 是报警阈值。

状态：

```text
NORMAL → DETECT → YIELD/WAIT → RELOCALIZE → RESUME → NORMAL
                      ↓
                 SAFE_PARK (timeout/retry)
```

让行条件：

```math
\text{yield} = \mathbf 1\!\left[d_{\mathrm{human}}<d_{\mathrm{safe}}\ \lor\ \tau_{\mathrm{tc}}<\tau_{\mathrm{stop}}\ \lor\ \text{object moved}\right].
```

稳定条件（连续 M 帧）：

```math
\mathrm{Var}(e_{t-M:t}) < \sigma^2.
```

恢复：重估 `T_base_target(t)`，用 CHUNK-SERVO 的相对目标 `T_target_ee*`，增益降档：

```math
K_{\mathrm{eff}} = K_0 \cdot \frac{1}{1+\tau/\tau_0}\cdot \rho_{\mathrm{resume}},\quad \rho_{\mathrm{resume}}\in[0.4,0.7].
```

### 2.4 双臂角色分配

代价矩阵：

```math
C_{ij} = \alpha\, d_{ij} + \beta\, \mathrm{occ}_{ij} + \gamma\, \mathrm{coll}_{ij} + \delta\, \mathrm{phase}_{ij},
```

`i∈{left,right}`，`j∈{stabilize,manipulate}`；2×2 用 Hungarian 求最小代价分配。仅当 `min C` 与当前角色差超过阈值时切换，避免抖动。

### 2.5 N 端口队列

请求 `i` 的 deadline：

```math
D_i = \frac{H_c}{f_c} + \tau_i,
```

`H_c` 是 chunk 步数，`f_c` 是控制频率，`τ_i` 是网络/推理延迟。调度目标：

```math
\max\ \mathrm{throughput}\quad \text{s.t.}\quad \mathrm{p99}(L_i)\le D_i,\ \forall i.
```

实现：EDF（earliest deadline first）+ 接触段优先 + 自适应批大小；队列过长时对非接触端口降级（用缓存 plan/降低伺服频率）。

### 3.3 `get_action` 主流程

```python
class SentinelPolicy:
    def get_action(self, obs):
        self.ledger.tick(obs)

        if self.yield_.should_yield(obs):
            chunk = self.yield_.override(obs)          # hold/retreat/release
            chunk = self.shield.filter(obs, chunk)     # still safety-check
            self.ledger.log("yield", self.yield_.reason)
            return self.adapter.to_api(chunk, obs)

        plan = self.plan_cache.get_or_request(obs)     # async 30-step VLA
        chunk = self.servo.correct(obs, plan[:self.H_c])  # CHUNK-SERVO

        if self.duet.conflict(obs, chunk):
            chunk = self.duet.arbitrate(obs, chunk)

        if self.rc_bon.enabled(obs):
            chunk = self.rc_bon.select(obs, chunk)     # same model, K samples

        chunk = self.shield.filter(obs, chunk)         # last veto
        self.ledger.log("action", chunk)
        return self.adapter.to_api(chunk, obs)

    def reset(self):
        self.plan_cache.clear()
        self.servo.reset()
        self.yield_.reset()
        self.duet.reset()
        self.shield.reset()
        self.ledger.new_episode()
```

规则：

- VLA 不阻塞 `get_action`（除冷启动）；plan 过期用旧 plan + 伺服。
- YIELD 可以绕过 VLA，但仍过 SHIELD。
- 任何异常 → 上一组合法 chunk/安全保持；绝不 NaN/错误形状。
- 每端口独立实例；共享 VLA 只按 session id 区分，不共享状态。

### 3.4 SHIELD：检查与平滑干预

```python
def filter(obs, chunk):
    if not valid(chunk):                 # NaN/shape/token
        return last_safe
    traj = rollout(obs.q, chunk)         # FK + 5-step prediction
    c_joint  = joint_limit_violation(traj)
    c_coll   = capsule_self_collision(traj)
    c_table  = below_table(traj)
    c_human  = human_distance_risk(traj, obs)
    c_smooth = jerk_violation(traj)

    if c_human > 0:
        return yield_.override(obs)      # yield has priority
    if c_coll > 0 or c_joint > 0:
        return scale_or_hold(chunk, obs) # slow/hold, keep last safe
    if c_smooth > 0:
        return blend(last_safe, chunk)   # 2-3 step blend
    return chunk
```

平滑混合：

```math
a_t = (1-\alpha_t)\,a_{t-1} + \alpha_t\,a_t^{\mathrm{cmd}},\qquad
\alpha_t \in \{0.3,0.6,1.0\}.
```

**Step-score-preserving fallback**：

```python
def safe_park(obs):
    if holding(obs):
        return place_at_nearest_stable(obs)   # table free area / scored zone
    return retreat_to_safe_pose(obs)          # above table, front, no collision
```

不假装成功；LEDGER 记录 `reason="unrecoverable"`。

### 3.5 YIELD：检测、让行、恢复

```python
def should_yield(obs):
    e = geo_residual.edit_score(obs)          # no learned weights
    self.cusum.update(e)
    if self.cusum.alarm or object_moved(obs) or human_near(obs):
        return True
    return False

def override(obs):
    if human_near(obs):
        return retreat_along_approach(obs, d=0.03) + open_gripper_if_empty()
    if object_moved(obs):
        return hold_position()                 # do not chase
    if object_taken(obs):
        return release_and_wait()              # do not fight
    return hold_position()
```

恢复：

```python
def resume(obs):
    if scene_stable(obs, M=5):
        target = relocalize(obs)               # head stereo + local ICP
        if target.visible and target.reachable:
            self.goal = target
            self.gain = 0.5 * self.gain0
            return True
    return False
```

超时：`T_wait > 5s` 或重试 `> 3` → `SAFE_PARK`。

### 3.6 DUET：角色、冲突、换手

```python
def conflict(obs, chunk):
    return (predicted_arm_distance(chunk) < d_min
            or predicted_occlusion(chunk)
            or gripper_slip(obs))

def arbitrate(obs, chunk):
    C = cost_matrix(obs, chunk)                # 2x2
    roles = hungarian(C)                       # {left: role, right: role}
    if roles != self.roles and C_gain > theta:
        self.roles = roles
    if predicted_arm_distance(chunk) < d_min:
        chunk = delay_lower_priority_arm(chunk, steps=3)
    if predicted_occlusion(chunk):
        chunk = reorder_arms(chunk)
    if gripper_slip(obs):
        chunk = handover_or_regrasp(obs, chunk)
    return chunk
```

换手位姿从演示检索：`T_handover = retrieve(task, phase="handover")`；置信度低则重抓，不换手。

### 3.9 控制频率与 chunk 选择

沿用 CHUNK-SERVO：

```math
T_{\mathrm{fb}} \approx \frac{H_c}{f_c} + \tau.
```

| 场景 | `H_c` | `f_c` | `τ` | `T_fb` |
|---|---:|---:|---:|---:|
| 官方默认 | 30 | 30 | 50ms | 1050ms |
| 本方案保守 | 5 | 30 | 50ms | 217ms |
| 高延迟 | 5 | 30 | 150ms | 317ms |
| 低控制频率 | 5 | 10 | 50ms | 550ms |
| 极低延迟 | 3 | 30 | 20ms | 120ms |

`H_c` 必须按实测 `f_c`/`τ` 选；安全层本身不改变 chunk，但 YIELD 可以在 chunk 边界插入 hold/retreat。

## 4. 伦理与合规设计

### 4.1 单模型合规的三种模式

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | GEO-RESIDUAL 只离线生成标签；线上只有 VLA | 最低 | 保守 |
| C2 确定性控制器 | SHIELD/YIELD/DUET/FLEET 是几何/控制律，无学习权重 | 低；需说明 | **主推** |
| C3 同 checkpoint 特征 | 视觉描述子用 VLA 同一 checkpoint encoder | 低–中 | 需要强描述子时 |

禁止：第二个学习策略/残差网络/独立视觉编码器做在线决策。

### 4.2 人机安全规则

- 人靠近：降速到 30%，沿接近轴后退 2–5cm，保持最小距离。
- 人拿走物体：松手，等待；不抢、不追。
- 人把物体放回：稳定 `M=5` 帧后重定位，保守增益恢复。
- 人不在视野：用本体/夹爪/任务状态兜底；不假设安全，保守停/等。
- 可读性：避免突然转向/高速靠近人；EE 低于肩高；动作方向可预测。
- 不做「假装安全」：检测置信度低 → 停/等，不赌。

### 4.3 数据与隐私

- 只用官方 33k 演示 + 仿真；不收集人脸/身份/生物特征。
- 人类扰动视频离线分析时匿名化/裁剪，只保留手/物体区域。
- 不把人类修正数据上传共享池；跨机器人只共享只读标定/案例。

### 4.4 评测诚信与责任披露

- 不利用榜单预览/占位视频/评分脚本漏洞；不伪造 run。
- 报告配对 A/B + bootstrap 95% CI；不 cherry-pick。
- 发现安全滤波器漏洞（参考 SIREN，arXiv 2610.31923）→ 先报告赛事方，不利用。
- 不把「安全停」算成功率；失败如实记录。
- 审计日志保留到赛后，支持复现与争议处理。

5. RC-BoN K=1/2/4（延迟/收益）。
6. 标定注册表 on/off（跨机器人方差）。
7. 平滑混合 on/off（动作统计异常）。
8. 人因检测：残差 vs 光流 vs 目标位姿（延迟/误报）。

## 6. 竞赛策略与收益

### 6.1 收益分解

| 来源 | 假设 | 全局收益 |
|---|---|---:|
| YIELD（human 轴） | 15% → 30% | +3.0pp |
| DUET（10 个双臂任务） | 各 +5pp | +1.6pp |
| FLEET（避免超时/断连） | 5% → 1% | +1.0–1.6pp |
| SHIELD（步骤分） | +3–5% 步骤分 | tie-break |
| RC-BoN（可选） | 接触任务 +2–3pp | +0.5–1.0pp |
| **合计** | 保守/乐观 | **+3–6 / +7–8pp** |

注意：320 trials 成功率标准误约 2.4pp；+1–2pp 不能当结论；必须配对 A/B + CI。

### 6.2 任务分档

- **H 档（人因/接触优先）**：HangCup、PlugInEthernet、DisconnectEthernet、Unlock、ZipUp、ArrangeTestTubes、StackBowls、PackPhone、OrganizePencilCase。
- **B 档（双臂优先）**：PackBag、ToolboxStorage、StorePaddle、StoreEarphones、PaperCupStacking、StoreCups、SyringeWaterTransfer。
- **V 档（VLA/语义优先）**：FruitSorting、ColorArrangement、OrganizeTools、FoldTowel、SpellRobot、ConveyorSorting。
- 优先级：`priority_t = (0.2×human_gain_t + bimanual_gain_t + step_gain_t) / cost_t`。

### 6.3 预算与时间表

| 阶段 | 时间 | 交付 | 退出条件 |
|---|---:|---|---|
| P0 基线 | 1 周 | WLA + CHUNK-SERVO + SHIELD + LEDGER | 单任务跑通 |

| P3 FLEET | 2 周 | N 端口/批处理/标定 | G4/G5 |

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 过度干预 | 成功率下降 | 默认放行；只在风险高时否决；A/B 门控 |
| 干预动作突变 | 动作统计异常/可信度下降 | 2–3 步平滑混合；限幅；记录原因 |
| 人手检测漏检 | 撞人风险 | 保守：不确定就停/等；双目+残差+光流多信号 |
| 误让行/等待过久 | human 轴反而下降 | 滞回；`T_wait` 上限；超时重规划 |
| 追物体 | 人机冲突 | 物体稳定 M 帧后再动；人拿走就松手 |
| DUET 破坏 VLA 协调 | 双臂任务下降 | 只在冲突预测时介入；直通默认 |
| 换手位姿不泛化 | 掉物 | 只在高置信时换手；否则重抓 |
| FLEET 共享后端瓶颈 | p99 超标 | EDF + 接触优先 + 自适应批；超时降级 |
| 状态泄漏 | episode 污染 | 每端口独立状态；reset 测试；无全局可变 |
| 标定漂移 | 伺服误差 | 每机器人残差；误差大关伺服；总体先验 |
| 单模型解释 | 被判违规 | 零学习权重；LEDGER；C1/C2/C3；提前沟通 |
| 安全滤波器参数错误 | 假安全 | 按任务配置；仿真故障注入；审计（SIREN） |
| 步骤分规则未知 | 优化错方向 | 以官方任务页/手册为准；不硬编码猜测 |
| 评测噪声 | 假阳性 | 配对 A/B；bootstrap CI；重复实验 |
| 安全漏洞被利用 | 伦理/合规风险 | 先报告赛事方；不利用 |
