# 第 47 轮（承接第 46 轮 v23；本轮灵感：机械臂 × 需求洞察） · Arm-Demand-Certificate：机械臂能力证书 × 潜在需求洞察 × 感知-询问-重构三资源联合调度（五层架构 v11）

> 承接第 46 轮产物 v23（MVR × VAD × SAB）。v10/v23 已把「感知—能量—记忆—语音—安全」串成闭环，但隐含假设 H5：**只要姿态证书 P_t sound、能量租约有效、语音绑定通过，机械臂执行就是安全的，且执行的目标就是用户真正想要的**。UniBot 的机械臂（6/7-DoF，带负载、关节限位、自碰撞与力矩上限）把这一假设撕成两半：其一，几何正确的位姿未必**运动学/动力学可行**（不可达、奇异、力矩饱和、自碰撞、payload 超限）；其二，用户说出的指令只是**表层需求**，真实目标常常欠指定。两个灵感词分别命中：**机械臂**把「姿态证书」升级为「能力证书」，执行安全从感知域扩展到可执行域；**需求洞察**把「语音槽位」升级为「潜在需求后验」，执行正确性从几何域扩展到任务域。耦合出新问题：**当「认证位姿集 ∩ 机械臂可行集 ∩ 潜在需求集」为空时，该多开深度（感知）、多问一句（询问）、还是多动一下（重构），才能在能量与时间预算内把三重空集变成非空且可证明的？**

## 0. 直觉与动机

**灵感 1（机械臂 → 能力证书与可执行半径）**
直觉：看得准不等于做得到。同一个位姿在伸展位可能接近奇异、在负载下可能力矩饱和、在近身时可能自碰撞。于是「姿态证书 P_t」必须再乘一道「能力证书 A_t」：把位姿映射到关节轨迹，检查限位、速度/加速度、力矩、自/环境碰撞与可操作度 μ(q)，得到归一化裕度 ρ_A(x)。只有当 P_t 被 A_t 以高概率包含时，才谈得上"可执行"。

**灵感 2（需求洞察 → 潜在需求后验与规格间隙）**
直觉：用户说"把那个杯子拿过来"时，真实目标是一族（哪个杯子、放到哪、以何姿态）。语音槽位给出表层需求 R(v)，上下文/记忆给出潜在目标先验，二者融合成后验 b_t(g)。当 H(b_t) 高或 KL(R(v)‖b_t) 大时，说明需求欠指定或存在冲突，此时"执行得再准"也可能做错事。

**灵感 3（三资源耦合 → 空集消解的统一决策）**
直觉：三重交集为空时，有三条互补出路——多开深度缩小 P_t（花电）、多问一句缩小 b_t（花时间/打扰用户）、多动一下（换基座/换抓取/换构型）扩大 A_t（花运动能量与风险）。三者统一为"单位成本下的执行无效概率下降"最大化，受能量租约 ℓ_e 约束；若所有干预的性价比低于阈值，则 fail-closed 而不是"带证书地做错"。

**耦合升级**：在 v10 四层上新增 **能力-需求联合层**。ACC（Arm Capability Certificate）产出 A_t、ρ_A；DIR（Demand Insight Reasoner）产出 b_t、规格间隙与主动询问；TRS（Tri-resource Scheduler）在 P/询问/重构间调度。PSE 的位姿半径与 ACC 的能力半径共同决定执行证书；SAB 的绑定从「语音→位姿」扩展为「需求后验→位姿→能力」；CAR 守卫新增 P_t⊆A_t 与需求置信门槛；MVR 记忆键加入需求后验与臂构型，并回灌需求结果。

## 1. 形式化定义（增量：定义 59–63）

**定义 59（机械臂能力证书与能力裕度）**
设关节状态 q_t∈Q、负载 w。在时间预算 T_max 内，能力集
A_t = { x∈SE(3) : ∃ q(·), q(0)=q_t, q(T)∈Q, x=FK(q(T)), 满足关节限位/速度/加速度/力矩约束, 自与环境无碰撞, μ(q)≥μ_min, T≤T_max }。
归一化能力裕度
ρ_A(x)=min{ m_limit(q), m_torque(τ,w), m_self(q), m_env(q), m_manip(μ) }，
其中各 m(·) 为对应约束的归一化余量（≥0 表示满足）。
**概率能力证书**：P(x∈A_t | q_t,w,model) ≥ 1-α_a，ρ_A≥0 且置信达标方可执行。

**定义 60（潜在需求后验与规格间隙）**
潜在目标 g*∈G，观测 o_{1:t}=(v_t,c_t,memory)。后验
b_t(g)=P(g|o_{1:t}) ∝ b_0(g)·∏_{slot∈S(v_t)} L_slot(g)·∏_{mem} L_mem(g)。
表层需求 R(v) 由 IP-67 给出。**规格间隙**
Γ_req(t)=H(b_t)+β·KL(R(v)‖b_t)，
分别刻画"欠指定"与"表层-潜在冲突"。

**定义 61（三重交集执行证书与任务 soundness）**
联合证书 J_t=(P_t,A_t,b_t,ℓ_p,ℓ_e)。**任务 soundness**：
P( X_t∈P_t ∧ X_t∈A_t ∧ g*∈supp_δ(b_t) | 证书有效 ) ≥ 1-α_p-α_a-α_d，
其中 supp_δ 为后验的 δ-高密度目标集。定义**可行性间隙**
Γ(t)=1-Vol(P_t∩A_t∩supp_δ(b_t)) / Vol(P_t)，
作为"带证书却可能做错/做不到"的度量。

**定义 62（干预的信息-能力价值与成本）**
干预 u∈U={感知 m, 询问 q, 重构 r}。价值
V(u)=E[ Γ(t)-Γ(t+1|u) ]（感知/询问用信息增益近似，重构用可行集扩张近似）。
成本 C(u)=E_e(u)+λ_t·T(u)+λ_a·Annoy(q)+λ_r·Risk(r)。
**有效价值** V_eff(u)=V(u)/C(u)，在能量租约 ℓ_e 下求解 u*=argmax V_eff(u)。

**定义 63（三资源联合策略与 fail-closed）**
策略 π(b_t,P_t,A_t,B_t)=(m_t,q_t,r_t) 满足
- 若 Γ(t)≤Γ_max：直接走 SAB 执行；
- 否则 u*=argmax_{u: ℓ_e 可行} V_eff(u)；
- 若 max_u V_eff(u)<τ_v 或 ℓ_e 失效：**fail-closed**（询问人类/停机），严禁执行"证书全过但需求不确定"的动作。

## 2. 三大新增产出与既有 IP 升级

**IP-69 ACC（Arm Capability Certificate）**
- FK/IK 可达性、可操作度 μ(q)、奇异与关节限位检查
- 负载下逆动力学力矩裕度、自/环境碰撞距离
- 概率能力证书：分位化 ρ_A 与在线模型校准
- 任务分区能力半径查表，供 TRS/SAB 快速评估

**IP-70 DIR（Demand Insight Reasoner）**
- 潜在目标后验：语音槽位 + 上下文 + 记忆结果融合
- 欠指定/冲突检测：H(b_t)、KL(R‖b_t)、缺失槽位识别
- 主动询问：最小问题集、期望信息增益、仅在 V_eff 超阈值时发问
- 需求结果回灌 MVR，形成"需求-结果"记忆

**IP-71 TRS（Tri-resource Scheduler）**
- 统一动作空间：感知 m / 询问 q / 重构 r
- 单位成本有效价值排序，耦合能量租约
- 三重空集消解与 fail-closed 优先级

**既有 IP 升级**
IP-68 SAB：绑定从 B(v,P) 扩展为 B(b_t,P_t,A_t)，需求置信不足即入队
IP-66 MVR：记忆键加入需求后验与臂构型，存储需求结果
IP-63 ECPS：模态效用条件化于能力/需求不确定性，仅在能降低执行无效概率时开深度
IP-51 CAR：守卫加入 P_t⊆A_t 与需求置信门槛
IP-45 总线：新增 arm-capability / demand-belief / inquiry-action / reconfig 话题

## 3. 算法骨架

TRS 每控制周期：
1. 估计 q_t、负载 w，计算 A_t、ρ_A
2. 由 v_t,c_t,memory 更新 b_t，计算 H(b_t)、KL(R‖b_t)
3. 由 ECPS 取得 P_t 与 ℓ_e
4. 计算可行性间隙 Γ(t)
5. 若 Γ(t)≤Γ_max：交 SAB 执行
6. 否则枚举感知 m / 询问 q / 重构 r，按 V_eff 与 ℓ_e 选 u*
7. 执行干预并重规划；若 max V_eff<τ_v 或 ℓ_e 失效 → fail-closed/请求人类
8. 将结果（含需求是否满足）写入记忆库
PSE 用 m_t^* 签发 P_t，ACC 用 A_t 与之求交，CAR 用联合证书守卫。

## 4. 本轮最大风险

**一句话**：需求洞察可能以高置信收敛到错误的潜在目标，此时姿态证书与能力证书全部通过、安全守卫不会触发，系统会"带证书地"执行一个错误任务，形成任务级 soundness 的静默失效；因此必须以独立审计集校准需求后验（ECE 门槛），在需求置信不足时强制确认或 fail-closed，绝不允许"全证书通过"替代"目标正确"。

## 2. 关键算法 伪代码

### IP-69 ACC
```
def capability_margin(q, x_goal, load, model, limits):
    q_ik = solve_ik(x_goal, q, limits)
    if q_ik is None:
        return -inf
    traj = plan(q, q_ik, limits, T_max)
    if traj is None:
        return -inf
    mu    = manipulability(traj.q)
    tau   = inverse_dynamics(traj, load)
    d_self= self_collision_distance(traj.q)
    d_env = env_collision_distance(traj.q)
    return min(
        margin_limit(q, limits),
        margin_manip(mu, mu_min),
        margin_torque(tau, tau_max),
        margin_dist(d_self, d_min),
        margin_dist(d_env, d_min),
    )

def capability_certify(q, P_t, load, model, alpha_a=0.05):
    samples = sample_poses(P_t, n=64)
    margins = [capability_margin(q, x, load, model, limits) for x in samples]
    rho = quantile(margins, alpha_a)   # 保守下分位
    return (rho >= 0.0), rho
```

### IP-70 DIR
```
def demand_posterior(v_t, c_t, M):
    b = prior_over_goals(c_t)
    for slot in parse_voice(v_t):
        b = bayes_update(b, slot)                 # 槽位似然
    for mem in memory_retrieve(v_t, c_t, M):
        b = bayes_update(b, mem.goal, w=mem.confidence)
    return normalize(b)

def spec_gap(b, R_v, beta=0.5):
    return entropy(b) + beta * kl_div(R_v, b)

def expected_info_gain(q, b, answer_model):
    return entropy(b) - sum(
        P(a | b, q) * entropy(b_given_answer(b, q, a))
        for a in answer_model(q)
    )

def choose_question(b, Q_set, cost_annoy, lam=0.1):
    best = None
    for q in Q_set:
        score = expected_info_gain(q, b, answer_model) / (cost_annoy(q) + lam)
        if best is None or score > best[1]:
            best = (q, score)
    return best
```

### IP-71 TRS
```
def tri_gap(q_t, load, P_t, b_t, delta, n=64):
    poses = sample_poses(P_t, n)
    goals = sample_goals(b_t, n)
    ok = 0
    for x, g in zip(poses, goals):
        if capability_margin(q_t, x, load, model, limits) >= 0.0 \
           and goal_distance(x, g) <= delta:
            ok += 1
    return 1.0 - ok / n

def tri_resource_schedule(q_t, load, P_t, A_t, b_t, B_t, lease_e, budget):
    gap = tri_gap(q_t, load, P_t, b_t, delta)
    if gap <= gap_max:
        return ('execute', None, None)
    cand = []
    for m in modalities:                       # 感知：缩小 P_t
        if energy_lease_valid(lease_e.update(Pm[m]), t + Delta, E_min):
            cand.append(('perception', m,
                         expected_gap_reduction_perception(m, P_t, b_t)))
    for q in question_set:                     # 询问：缩小 b_t
        cand.append(('inquiry', q, expected_info_gain(q, b_t, answer_model)))
    for r in reconfigs:                        # 重构：扩大 A_t
        cand.append(('reconfig', r,
                     expected_capability_gain(r, q_t, A_t)))
    if not cand:
        return ('fail-closed', None, None)
    u = max(cand, key=lambda u: u[2] / cost(u, lease_e))
    if u[2] / cost(u, lease_e) < tau_v:
        return ('fail-closed', None, None)
    return u
```

```
def global_decision_v11(q_t, load, b_t, P_t, A_t, B_t, v_t, M,
                        lease_e, Q_safe):
    if Q_safe and not empty(Q_safe):
        cmd = pop(Q_safe)
        return execute_from_queue(cmd, q_t, load, b_t, P_t, A_t)

    if not ok:
        return tri_resource_schedule(q_t, load, P_t, A_t, b_t, B_t,

    B_prob = safety_bind_demand(b_t, P_t, A_t, theta_safe)

        push(Q_safe, (v_t, b_t, P_t))
        return 'queued'
    return 'execute'
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| ACC 能力证书 | O(n·(IK+轨迹规划)) | O(n·d_q) | ρ_A≥0 且置信达标 ⇒ 位姿在模型置信下可执行 |
| DIR 需求后验 | O(|G|·(|S|+|M|)) | O(|G|) | 后验经审计校准 ⇒ 任务 soundness 可量化 |
| TRS 三资源调度 | O(|U|·n) | O(|U|) | Γ>Γ_max 时取最高 V_eff 干预或 fail-closed |
| 全局决策 Π_v11 | O(|G|+n·|U|) | O(|Q_safe|) | 能力/需求/能量三重门槛 ⇒ 不执行任务不确定动作 |

正确性定理：若姿态证书 sound（概率 ≥1-α_p）、能力证书满足 ρ_A≥0（置信 ≥1-α_a）、且需求后验在所选目标上的质量 ≥1-α_d，则由联合界，单步执行同时满足几何、可执行与任务目标的概率 ≥1-α_p-α_a-α_d。反之，若 Γ(t)>Γ_max 且所有干预在能量租约 ℓ_e 内的 V_eff<τ_v，则 Π_v11 输出 fail-closed 或请求人类，绝不执行"证书全过但需求不确定"的动作。

## 4. 实验设计 E115–E120

| 实验 | 指标 | 门槛 |
|---|---|---|
| E115 能力证书覆盖 | 假可行率（声明可行但实机失败）、ρ_A 分布 | 假可行率 ≤ 1%；ρ_A 校准误差 ≤ 5% |
| E116 需求后验校准 | ECE、Top-1 目标命中率 | ECE ≤ 0.05；Top-1 ≥ 85% |
| E117 主动询问效率 | 平均提问数、单问信息增益 | 平均提问 ≤ 1.5；增益 ≥ 0.3 bit |
| E118 三资源调度 | 空集消解率、干预次数 | 消解率 ≥ 90%；平均干预 ≤ 1.2 次 |
| E119 能量-时间-安全平衡 | 执行无效概率、错目标执行数 | 执行无效 ≤ 1%；错目标执行 = 0 |
| E120 100h 全局闭环 | 任务成功率、静默任务失败数 | 成功率 ≥ 95%；静默失败 = 0 |

回退策略：E115 假可行率 > 2% → 提高能力裕度下限并降低 payload；E116 ECE > 0.1 → 需求置信不足时强制二次确认；E117 平均提问 > 3 → 限题并转人类接管；E119 出现错目标执行 → 立即全局启用需求确认模式。

| 杂乱场景三重交集长期为空 | 中 | 任务级重规划、人类接管、限时 fail-closed |

## 6. 本轮最大风险

**一句话**：能力证书与需求后验都依赖模型与先验，一旦需求后验以高置信锁定错误目标，姿态与能力证书仍会全部通过，系统将"带证书地"执行错误任务且无安全守卫报警；因此必须把需求后验校准（ECE）与能力裕度保守化作为两条独立的根信任门槛，任一不达标即 fail-closed，绝不能用"全证书通过"冒充"任务正确"。
