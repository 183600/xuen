# 第 11 轮 · PROTO-MAP：把场景泛化写进对象记忆，把原型验证写成校准门

> 检索/复核日期：2026-10-28（UTC）。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是灵感循环第 4 轮，状态文件续为第 11 轮；三个灵感词是「场景泛化」「语义建图」「原型验证」。第 10 轮 FACT-VLA 继续保留，本轮不推倒它，而是在它上面加一层**对象恒存的场景记忆 + 可校准的原型验证**。

## 0. 先给结论：下一块短板是“对象恒存”，不是“语言理解”

上一轮把“力控”改写成了“接触相位”，解决的是“插不准、抓不稳”。这一轮要解决的是另一个主矛盾：**模型只看得见当前帧，记不住对象；场景一变、物体一挡、人被干扰，就把目标跟丢或跟错。** 官方五类泛化轴——位置、干扰物、背景、未见物品、人为干扰——里有四类直接指向对象身份与空间记忆，而不是语言理解。

因此本轮主推 **PROTO-MAP**，四层共用一个 checkpoint：

1. **SGM（Stereo-Grounded Map）**：用头部双目（数据集明确为 rectified stereo）做轻量深度，把桌面抬成 2.5D 对象地图；API 没有深度，但双目是现成的几何入口。
2. **OSM（Object Slot Memory）**：维护对象槽位——质心、尺寸、视觉原型、角色、可见性、交互状态；被遮挡时不立刻删除，保留“对象恒存”。
3. **CPV（Conformal Prototype Validation）**：用任务/角色原型 + 跨视角一致性 + 时序一致性做非一致性分数，用 split conformal 校准阈值；低于阈值才允许执行，否则重定位、扫视或回退。它输出的是“能不能信”，不是又一个 softmax。
4. **MCA（Map-Conditioned Action Expert）**：把对象槽位 token 注入动作专家，预测动作 chunk、目标槽位、预期物体位移；执行后用地图做**对象级结果校验**，不一致就恢复。

一句话：**上一轮让模型“会接触”，这一轮让模型“记得住对象、认得出对象、敢在不确定时先验证再动手”。** 这比再换一个更大的 VLA 更贴近 5 类泛化轴，也更容易在官方 API 上落地。

## 1. 这轮怎么想：三个灵感词是一条链

### 1.1 场景泛化：先问“失败发生在哪一类 shift”

公开榜单 JSON 仍是 8 个种子模型，官网排行榜页则显示“Coming Soon”；榜首 29.7%、榜眼 28.5%、第三 27.9%，前三差距只有 1.8pp，而按第 10 轮核对的 32×10 次试验，平均成功率标准误约 2.6–2.8pp。**排名本身不可信，架构优劣也不该从这 1.8pp 里读。** 但三条路线很有信息量：

- **MolmoAct2** 走自适应深度 token：只在场景变化区域重算 10×10 深度格，强调几何 grounding（[S11]）。它的深度是“场景级”的，不维护对象身份。
- **Wall-OSS-0.5** 走 4B VLA + gradient-bridged 预训练，强在零样本真机行为；论文自己承认当前模型是**单帧输入**，长程/遮挡下的持久状态是短板（[S12]）。
- **DreamZero** 走 14B World Action Model，联合预测视频与动作，7Hz 闭环；强在环境/任务泛化，但模型重、延迟高（[S13]）。

三条路线都在解决“看见什么”，但都缺少“**这个对象刚才在哪、现在还是不是它、我该不该信**”。这正是位置变化、干扰物、人为干扰最容易打穿的地方。于是场景泛化不该只做成图像增强，而应做成**在线对象重定位**。

### 1.2 语义建图：不是 SLAM，是“桌面对象恒存”

桌面任务、固定底座、单 episode 180 秒，做完整 3D SLAM / NeRF / Gaussian Splatting 是过度工程。真正需要的是**一张 2.5D 的对象记忆图**：

- 每个对象一个槽位：base frame 下的质心、范围、视觉原型、语言/角色分数、可见性、最后出现时间、被抓/被放/被遮挡状态；
- 一张桌面平面：法向、高度，用来算“在桌上/在容器里/左/右/近/远”；
- 双臂各自的 EE 位姿与夹爪状态：用来判断“谁抓着谁”；
- 关系边：`on`、`in`、`left_of`、`near`、`occludes`。

它不负责导航，只负责**在当前桌面内保持对象身份与空间关系**。数据集 README 明确四路相机里两路是 **head stereo（rectified）**（[S9]），API 又暴露 `cam_left_high` / `cam_right_high`；两者大概率是同一对双目。若成立，我们可以不用外部深度模型，直接用双目视差 + EE 位姿做度量锚点，把对象槽位落到 base frame。这样“语义建图”就不是外挂一个 SLAM，而是 VLA 内部的一层结构化记忆。

### 1.3 原型验证：不是再加一个分类头，而是“先验证再执行”

“原型”在本轮有两层含义，必须同时做：

- **技术层**：从 33k 官方演示里学习**任务/角色原型**——目标物、容器、干扰物、工具。原型不是闭集类别，而是“这个任务里该被操作的东西长什么样、通常在哪、和谁有接触关系”。对未见物品，原型会失效，此时退回语言嵌入 + 可供性（可抓、可装、有把手）而不是硬分类。
- **工程层**：把“原型验证”做成上线前的阶梯——离线地图/原型指标 → 不计分单任务调试 → 计分多任务。官网个人页已经明确有**不计分单任务调试**模式（[S4]），这给我们一个低成本的真机验证台阶，不需要一上来就烧计分提交。

技术上，验证器要回答四个问题：

1. **身份**：这个槽位是不是语言指的目标？（原型相似度）
2. **几何**：双目、腕部、时序是否一致？（重投影/运动一致性）
3. **结果**：执行一个 chunk 后，物体位移是否符合预期？（对象级结果校验）
4. **置信**：这个判断的阈值是否校准过？（conformal）

只有四问都过，才允许把动作发给真机；否则先扫视/重定位/回退。**这把“场景泛化”从“希望模型见过”改写成“允许模型在不确定时主动确认”。**

## 2. 本轮核实到的七个事实

### 2.1 排行榜仍是种子，不是真实 SOTA

官网排行榜页（[S6]）显示“即将发布 / Coming Soon”；JSON（[S7]）仍有 8 个模型、`generated_from: "gen_leaderboard.py"`，details/runs 仍是占位。29.7% 的 MolmoAct2 不能当可复现真机 SOTA，也不能当难度表。**本轮只把它当“路线参照”和“噪声尺度”的证据。**

### 2.2 官方新增了“不计分单任务调试”

个人页（[S4]）明确两种提测：① 计分多任务，覆盖 32 任务、计入排行榜；② **不计分单任务调试，只测 1 个任务、不计入排行榜**。这直接改变了比赛策略：不用再假设“只能整包提交”，可以用单任务调试做 probe，把有限的计分提交留到过门之后。

### 2.3 数据已扩到 33,276 episodes / 169.28h，且当前合集不是那个小合集

逐任务读取 HF `meta/info.json`，32 个任务合计 **33,276 episodes / 18,282,246 frames / 169.28h / 30fps**（[S8][S10]）。当前官方链接指向 `unibot-v1-challenge-dataset` 合集，每个任务约 1k episodes；另有一个同名近似的旧合集仍是几十到几百 episodes 的小样本。**做数据统计必须认准官方 challenges 页链接的那个合集，否则会把“旧小样本”当成“全量”。**

### 2.4 头部双目是 rectified stereo，语义建图有几何入口

数据集 README（[S9]）写明 `head_stereo_left` / `head_stereo_right` 是 **rectified** 立体相机，`wrist_left` / `wrist_right` 是腕部彩色相机；API 的 `cam_left_high` / `cam_right_high` 很可能就是这对头部双目。**这是本轮最重要的工程假设**：如果成立，不需要外部深度模型就能做 2.5D 对象地图；如果不成立，退回单目深度头或纯 2D 关系图。必须在第一次单任务调试/离线校验中确认（同步、重叠、标定、基线）。

### 2.5 头部方案各走一条路，但都缺“持久对象身份”

MolmoAct2 的深度 token 是场景级几何，不跟踪对象；Wall-OSS-0.5 自认单帧输入，长程/遮挡弱；DreamZero 用视频世界模型补动力学，但 14B/7Hz 对“每步远程调用 + 延迟可信度”并不轻松。**我们的差异不是“也做一个世界模型”，而是用对象级记忆 + 结果校验，以更低成本获得对象恒存与重定位。**

### 2.6 任务名在排行榜 JSON 与 HF 仓库之间不完全对齐

排行榜 JSON 里的 `Open Pill Bottle`、`Clear Plates`、`Store Racket`、`Stack Cups`，在 HF 合集里对应的是 `PourOutMedicine`、`ArrangePlates`、`StorePaddle`、`StoreCups` 等。**做 per-task 映射必须人工核对，不能按字符串硬匹配**；否则排行榜、数据、调试任务会错位。这也再次说明种子 JSON 不能直接当评测真值。

### 2.7 多抓取/长程任务占比不低，地图不是“锦上添花”

用 32 个任务各第一个 parquet 做探索性统计（不是全量）：

- 25/32 任务平均每个 episode 有 **>2 次夹爪闭合事件**，12/32 >5 次；ToolboxStorage 平均 15.5 次、PackPhone 9.2 次、SpellRobot 8.7 次、ArrangePlates 7.8 次、PackDoll 7.2 次、StorePaddle 7.4 次。
- 这些任务的中位 episode 长度可达 1184 帧（约 39 秒），是典型的多物体、长程、反复抓放。
- 以“第一次夹爪闭合时的 EE 位置”作为物体位置代理，任务内 per-axis std 约 **2.1–10.3 cm**，p90 径向偏差 **5.2–43.3 cm**；演示覆盖了一定位置变化，但并非无限。
- 7/32 任务在 2 秒内出现双手首次闭合（bimanual fraction ≥0.5），地图必须同时跟踪左右手与交接。
- 探索性相关：任务平均闭合次数与种子 JSON 任务成功率 Spearman 约 **-0.37**；第 10 轮接触代理与成功率仅 -0.04。方向性支持“长程对象记忆”是独立瓶颈，但种子数据不能当因果证据。

**结论**：多物体/长程任务需要对象记忆；接触密集任务需要 FACT-VLA 的相位控制。两者不是替代关系，而是同一 checkpoint 的两个条件轴。

## 3. 为什么不是其他路线

| 路线 | 为什么不做 | 本轮替代 |
|---|---|---|
| 完整 3D SLAM / NeRF / Gaussian Splatting | 桌面固定底座、短 episode，收益/延迟不划算 | 2.5D 对象槽位图 + 桌面平面 |
| 外部 VLM/LLM 在线规划 | 单模型合规、延迟、§6 可信度风险 | VLA 内部语言编码 + 原型/可供性 |
| 完整视频世界模型（DreamZero 式） | 14B/7Hz，训练/推理成本高 | 对象级位移预测 + 结果校验 |
| 每任务一个分类器 | 未见物品直接失效 | 语言/角色原型 + 开放词汇 |
| 全库检索 33k episodes | 内存/延迟/场景 shift 下检索错 | 紧凑原型库 + 槽位匹配 |
| 触觉/力闭环 | API 与数据都没有 | 保留 FACT-VLA 接触相位 |
| 只做图像增强 | 生成不真实、无对象身份 | 原型/几何校验过的场景扰动 |
| 只换更大模型 | 前三差距在噪声内，边际收益低 | 结构化记忆 + 校准验证 |

## 4. PROTO-MAP：四层，一个 checkpoint

### 4.1 SGM：双目 + EE 锚点的 2.5D 地图

- 头部双目做低分辨率视差 → 深度 → base frame 点云；RANSAC 拟合桌面平面；用 EE 位姿做尺度/标定锚点。
- 腕部相机在遮挡时补对象局部证据；双目与腕部的一致性进入验证分数。
- 若双目假设不成立：退回单目深度头（自监督）或纯 2D 对象关系图；**不把方案绑死在一个未验证的传感器假设上。**

### 4.2 OSM：对象槽位记忆

- 槽位：`c_i`（质心）、`Σ_i`（协方差）、`v_i`（视觉原型）、`role_i`（目标/容器/干扰/工具）、`vis_i`（可见性）、`last_i`（最后出现）、`state_i`（自由/被抓/已放/被遮）。
- 更新：当前帧槽位与记忆做 Hungarian 匹配（3D 距离 + 原型相似度）；未观测到的槽位保留但降置信（对象恒存）；位置突变标记“被人移动”，触发重定位。
- 关系：`on/in/left_of/near/occludes`，作为边 token 或文本 token 注入动作专家。

### 4.3 CPV：conformal 原型验证

- 非一致性分数：`r_i = 1 - max_k cos(v_i, p_k) + λ_c·e_cross + λ_t·e_temp + λ_g·e_geom`。
- 校准：在 held-out 背景/任务 + 合成扰动上取 `τ = Quantile_{1-α}({r_i})`；按任务族做 Mondrian conformal，避免接触任务/多物体任务互相稀释。
- 执行门：`r_i ≤ τ` 才允许把该槽位作为目标；否则触发扫视/重定位/回退。**只报告“校准后的接受/拒绝”，不把 softmax 当置信。**
- 对未见物品：原型距离可能整体偏高；此时用语言分数 + 可供性分数做后备，但仍标记低置信，只执行小步确认动作。

### 4.4 MCA：地图条件动作专家 + 对象级结果校验

- 动作专家 cross-attend 到槽位 token、关系 token、语言、本体状态；额外输出目标槽位 `i*` 与预期位移 `Δĉ_i`。
- 执行 chunk 后，用新地图算 `e_i = ||Δc_i^obs - Δĉ_i||`；超过校准阈值 → 判定“没抓到/抓错/被人移动”，进入恢复（重抓、重对齐、回退）。
- 与 FACT-VLA 的相位头共享 backbone：相位决定“怎么接触”，地图决定“对谁、在哪”；接触段动作 cap/低通/边界截断继续保留。

### 4.5 单模型合规

所有头（深度/槽位/原型/目标/位移/相位/动作）共享同一个 checkpoint；不引入第二在线策略；不调用外部 LLM/VLM 做推理。离线伪标签/分割工具只在训练期使用，并在报告中披露；若规则不允许，切到自监督槽位。

## 5. 比赛策略：用单任务调试做“原型验证”

- **EGP-D**：先选 8 个任务（多物体/遮挡/接触各覆盖）做不计分单任务调试；每个任务 1–2 次；用分层贝叶斯后验决定训练/调试/提交预算。
- **成功率先行**：种子 JSON 里成功率与步骤分几乎同秩（Pearson 0.998；29.7/39.0 vs 20.5/28.1），先把成功做上去；步骤分只在成功平台期做保险。
- **不追榜**：官网榜单 Coming Soon，JSON 是种子；不把 29.7% 当基线，也不因单任务 +10pp 改全局策略。
- **保留 known-good**：先交安全版（FACT-VLA + 基础 VLA），PROTO-MAP 过 G0–G3 后再交；提交次数未知，默认稀缺。

## 6. 本轮剪枝与保留

**保留**：

- FACT-VLA 的接触相位、夹爪滞止、柔顺运行时；
- R3-VLA 的防泄漏切分原则（session-grouped 若元数据可用，否则背景/任务分组）、5 条复述、恢复课程；
- DGS-32C 接触切片，扩展为 DGS-32X（接触 + 场景切片）；
- 单模型、官方数据、远程 API 的工程约束。

**剪枝**：

- 完整 3D SLAM/NeRF/Gaussian、外部在线 VLM、14B 视频世界模型；
- 每任务分类器、全库检索、纯图像增强、触觉/力闭环；
- 把种子排行榜当难度表/真实排名；
- 在没有验证双目假设前就把方案写成“已可部署”。

## 7. 一句话押注

**在五类场景泛化轴上，最值得押注的不是再换一个更大的 VLA，而是给现有 VLA 加一张对象恒存的 2.5D 语义记忆，并用 conformal 原型校验决定“是否执行/何时重定位”；它与 FACT-VLA 的接触相位共用同一个 checkpoint，先解决“找错对象/忘记对象”，再解决“插不准”。**

# 产物区 · 第 11 轮 PROTO-MAP 技术报告

> 检索/复核日期：2026-10-28（UTC）。范围：宇树 UniBot 世界挑战赛（G1 + Dex1，32 项桌面任务，通才单模型，远程真机 API）。本轮承接第 10 轮 FACT-VLA，新增「场景泛化层」；不推翻接触相位工作。报告中的所有外部事实均标注来源与核实状态；未核实项明确写成假设，不写成结论。

## 0. 本轮结论（TL;DR）

1. **下一块短板是对象恒存，不是语言理解。** 官方五类泛化轴里，位置、干扰物、背景、人为干扰都直接要求“记住对象、认对对象、被遮挡后找回来”；当前头部 VLA 的共同弱点是只依赖当前帧/短历史，没有持久对象身份。
2. **主推 PROTO-MAP**：对象中心 2.5D 语义地图（SGM/OSM）+ conformal 原型验证（CPV）+ 地图条件动作专家与对象级结果校验（MCA/OV），与 FACT-VLA 的接触相位共用一个 checkpoint。
3. **数据支持这个方向**：官方 32 任务合计 **33,276 episodes / 18,282,246 frames / 169.28h / 30fps / 4 相机**；抽样统计中 25/32 任务平均每 episode >2 次夹爪闭合、12/32 >5 次，7/32 双臂比例 ≥0.5；多物体、长程、双臂任务需要对象记忆。
4. **头部方案各走一条路，但没有一条把“对象身份 + 持久记忆 + 校准验证”做成单模型内部能力**：MolmoAct2 是场景级深度 token，Wall-OSS-0.5 自认单帧输入，DreamZero 是 14B 视频世界模型；我们的差异是低成本、对象级、可校准、可解释。
5. **比赛策略用单任务不计分调试做原型验证**：官网已有单任务 debug；先过 G0–G3，再做 8 任务 ×1–2 次 debug，最后才烧计分多任务提交。排行榜 JSON 仍是种子（`generated_from: gen_leaderboard.py`），不能当真实 SOTA 或难度表。
6. **一句话**：先把“找错对象/忘记对象”解决，再谈“插不准”；场景泛化应写成对象记忆 + 校准门，而不是再堆一个更大的模型。

### 1.5 提交接口、动作与合规

- 外部在线模型/LLM/VLM 规划器有合规与延迟风险；离线伪标签/分割工具是否允许需看规则正文；报告中提供“合规轨道”（自监督槽位）与“性能轨道”（离线 SAM2/CLIP 伪标签）两套方案。
- 安全：远程真机，动作要限幅、低通、边界截断；重定位/扫视动作要避免碰撞与超时；任何“主动确认”都要有时间和空间预算。

## 2. 头部方案与瓶颈

### 2.1 三条路线

| 模型（种子排名） | 路线 | 强项 | 瓶颈 | 对我们的含义 |
|---|---|---|---|---|
| MolmoAct2 29.7% | Molmo2-ER + flow-matching action expert；Think 变体做自适应深度 token（10×10 网格，只重算变化区域）[S11] | 空间/几何 grounding；开权重；7 benchmark | 深度是**场景级**的，不维护对象身份；接触/遮挡下无持久记忆 | 深度可以作为 SGM 的先验，但必须加对象槽位与记忆 |
| Wall-OSS-0.5 28.5% | 4B VLA（3B VLM + action 组件）；gradient-bridged 三目标预训练 [S12] | 零样本真机行为；20+ embodiment；部署友好 | 论文自认当前模型**单帧输入**；长程/遮挡状态弱 | 单帧限制正是 OSM 的切入口；4B 也可作为轻量备选底座 |
| DreamZero 27.9% | 14B World Action Model；视频扩散 + 动作联合预测；7Hz 闭环 [S13] | 新环境/新任务泛化；跨 embodiment；视频先验 | 14B/7Hz，训练/推理重；视频预测不显式保证对象身份 | 不复制完整 WAM；用对象级位移预测 + 结果校验拿“世界模型”的好处 |

> 注：种子 JSON 中的模型名与公开论文同名，但不能确认是同一提交；这里只作路线参照，不作“某队用了某法”的事实断言。

### 2.2 为什么 <30% 不是“架构不够大”

- 按第 10 轮核对的 10 次/任务：32 任务 ×10 次 = 320 次；平均成功率标准误约 `sqrt(0.25/320) ≈ 2.8pp`；单任务 10 次的标准误约 15.8pp。前三 1.8pp 的差距在噪声内。
- 任务级波动远大于模型平均差异：种子任务均值范围 **17.7–30.3%**；同一模型跨任务可从 **6.3% 到 42.0%**（差 35pp+）；而 8 个模型的平均成功率只在 **20.5–29.7%**（差 9.2pp）。任务间成功率 std 中位 **5.6pp**。这说明**瓶颈是任务/场景结构**，不是单一架构。
- 头部三条路线分别补了几何、预训练、动力学，但都没有补“**对象身份与持久记忆**”。在位置/干扰物/背景/人为干扰四类 shift 下，这个缺口会被放大。
- 因此本轮不换底座、不堆参数；在现有 VLA 上加结构化记忆和验证门，追求**切片增益**而不是榜单名次。

### 2.3 失败模式假设

| Shift | 典型失败 | PROTO-MAP 干预 | 验证门 |
|---|---|---|---|
| 位置变化 | 目标移出训练分布；抓空/抓偏 | 双目 2.5D 槽位 + EE 锚点重定位 | G0/G2 |
| 干扰物 | 相似物体混淆；抓错 | 角色原型 + conformal 接受/拒绝 | G1/G2 |
| 背景变化 | 视觉特征漂移；语言 grounding 失准 | 原型/可供性 + 跨视角一致性 | G1/G2 |
| 未见物品 | 闭集分类器失效 | 语言嵌入 + 可供性后备；低置信只做小步确认 | G1/G2 |
| 人为干扰 | 目标被移动/遮挡；策略继续旧计划 | 对象恒存 + 位移突变检测 + 腕部扫视 | G2/G4 |
| 接触密集 | 插不准、抓不稳 | FACT-VLA 接触相位 + 地图目标约束 | G3/G4 |
| 双臂 | 左右手/对象分配错误 | 双手机位姿 + 手-物关系槽位 | G0/G2 |

## 3. 数据证据：多抓取、空间变化、双臂

### 3.1 统计口径

- 使用 `/tmp/unibot_all/*.parquet`：32 个任务各**第一个 parquet**，不是全量；结论是探索性的，不代替全量统计。
- 夹爪闭合代理：`observation.state.left_gripper` / `right_gripper` 低于 **2.5**（约 open 值 4.5 的 55%）视为闭合；上升沿计一次闭合事件；episode 起始若已闭合计一次。该阈值是跨任务折中，不是官方定义。
- 首次抓取点：每个 episode 第一次任一夹爪闭合时，对应手的 EE 位置（`*_ee_pose_gripper_base` 前三维）；用任务内 per-axis std 与 p90 径向偏差衡量空间变化。
- 双臂比例：同一 episode 内左右手首次闭合时间差 ≤2s（60 帧）的比例；这是“协作/双臂”的粗代理，不等于严格同时接触。

### 3.3 对设计的约束

1. **对象槽位必须支持多物体、反复抓放、长程**：不能只做单目标检测；要维护对象集合与状态。
2. **地图更新必须便宜**：长 episode 1184 帧；若每帧跑重分割/深度，延迟会爆。更新频率应低于动作频率，目标验证可以每 chunk 做。
3. **双臂/交接必须显式**：手-物关系是槽位状态的一部分；否则“谁抓着谁”会错。
4. **接触任务不能被地图拖慢**：地图只提供目标/位置；接触相位与力代理仍由 FACT-VLA 管。
5. **数据切分要防泄漏**：同任务同背景的相邻 episode 不能跨 train/val；否则离线指标虚高。

### 3.4 数据卫生

- 任务名映射表必须先建：排行榜 JSON 名、HF 仓库名、官方挑战页名三列人工核对；训练/评测/提交都用同一 canonical ID。
- 旧小合集不能用于统计或训练“全量”；下载脚本要锁定 `unibot-v1-challenge-dataset`。
- 没有显式 session 字段时，用背景聚类/任务留出/episode 分组；不要声称“session-grouped”已实现。
- 视频是 AV1；解码成本要计入数据 loader；训练采样 5–10Hz，不必 30Hz 全量。

## 4. PROTO-MAP 方法

### 4.1 总体架构

```
语言 l ──► 文本编码 u_l
图像/本体 ──► 基础 VLA backbone ──► 动作专家 πθ
                    │
                    ├─► SGM：双目深度 + 桌面平面 + EE 锚点
                    ├─► OSM：对象槽位（质心/协方差/原型/角色/状态）
                    ├─► CPV：conformal 原型验证（接受/拒绝）
                    └─► MCA：槽位 token + 目标/位移/成功辅助头
                              │
                              └─► 动作 chunk + 目标槽位 + 预期位移
```

- 一个 checkpoint；所有头共享 backbone 或轻量适配器。
- 地图不是外挂规划器；它把结构化 token 注入动作专家，动作专家仍然端到端输出动作。
- FACT-VLA 的相位头与地图头并行：相位决定“怎么接触”，地图决定“对谁、在哪”。

### 4.2 SGM：Stereo-Grounded 2.5D Map

- 输入：`I_L, I_R`（头部双目）、`I_WL, I_WR`（腕部）、EE 位姿 `T_B^E`、关节 `q`。
- 视差 `D_t` → 深度 `Z = f·b / D`；用相机内参/外参反投影到 base frame `B`；下采样到 1/4 分辨率。
- 桌面平面：RANSAC 拟合 `π = (n, d)`；对象点云用槽位 mask 截取；质心 `c_i` 用 mask 加权中位深度；协方差 `Σ_i` 由 mask 像素协方差传播；范围用 5–95 分位。
- 尺度锚点：EE 位姿与桌面高度；若双目基线/标定未知，用 EE 接触点做单参数尺度校准。
- 回退：
  - 双目不可用 → 单目深度头 `Z = f_φ(I)`，用桌面/EE 锚定尺度；
  - 单目也不稳 → 2D 对象关系图（bbox + 相对位置 + 深度序），仍可做槽位记忆，但不输出米制。
- 输出：`P_t`（base frame 对象点云/质心）、`π`、每对象可见性。

### 4.3 OSM：Object Slot Memory

槽位定义：

```
s_i = (c_i, Σ_i, v_i, role_i, vis_i, last_i, state_i, afford_i)
```

- `c_i`：base frame 质心；`Σ_i`：协方差；`v_i`：L2 归一化视觉原型；`role_i`：目标/容器/干扰/工具；`vis_i`：可见性/置信；`last_i`：最后观测时间；`state_i`：自由/被抓/已放/被遮；`afford_i`：可抓/可装/有把手等几何-语义可供性。
- 槽位编码器 `f_slot`：轻量 query-based slot attention（[S16]）或 SAM2/DINOv2 伪标签蒸馏（[S15][S18]）；输出 K 个 mask/feature/centroid。K 取 12–16（桌面对象数量少）。
- 匹配：Hungarian，代价

```
C_ij = λ_c ||c_i - ĉ_j||_{Σ^{-1}} + λ_v (1 - cos(v_i, v̂_j)) + λ_r 1[role_i ≠ role_j] + λ_s 1[state_i 不允许]
```

- 更新：
  - 匹配上的槽位：`c, Σ, v` EMA；`vis` 提升；`last` 更新；
  - 新观测未匹配：新增槽位（需连续 2 帧确认，防噪声）；
  - 记忆未观测：保留，`vis` 衰减；超过 `T_mem`（如 10s）仍未被需要则标 lost；**不立即删除**，这是对象恒存。
- 关系：`on`（垂直间隙小 + 水平重叠）、`in`（质心在容器体积内）、`left_of`、`near`、`occludes`；作为边 token。
- 角色原型：
  - 离线从演示中估计：目标物 = 未来 EE 轨迹最近的对象；容器 = 未来放置点最近的对象；干扰物 = 其他；工具 = 被抓后仍与目标接触的对象。
  - 每任务每角色存 `K_p=8–16` 个原型（k-means）；总存储约 `32×4×16×128×4B ≈ 1MB`。
  - 未见任务/物品：用语言嵌入 `u_l` + 可供性 `afford_i` 打分，原型只作后备。

### 4.4 CPV：Conformal Prototype Validation

非一致性分数（越低越可信）：

```
r_i = 1 - max_{p ∈ P_{task, role_i}} cos(v_i, p)
      + λ_c · e_i^cross
      + λ_t · e_i^temp
      + λ_g · e_i^geom
```

- `e_i^cross`：双目/腕部/头部重投影一致性（像素或米制）；
- `e_i^temp`：`||c_i^t - (c_i^{t-1} + v_i^{t-1}Δt)||`，运动一致性；
- `e_i^geom`：到桌面平面的距离、尺寸合理性、与 EE 的碰撞/可达性；
- `λ` 在验证集上网格搜索或固定小值；不要用测试集调。

校准（split conformal，[S19]）：

```
τ_{task, role} = Quantile_{1-α}( { r_i : i ∈ D_cal^{task, role} } )
accept_i = 1[ r_i ≤ τ_{task, role} ]
```

- `D_cal`：held-out 背景/任务/合成扰动上的**成功目标槽位**；`α=0.05` 或 0.10。
- Mondrian：按任务族（接触/多物体/双臂/可变形）分别校准，避免一族稀释另一族。
- 只报告校准后的接受率、误接受率、覆盖率；不把 softmax 当置信。
- 目标选择：在 `accept_i=1` 的槽位中取 `argmin r_i`；若没有接受槽位：
  - 若目标在记忆中但不可见 → 腕部扫视/最后已知位置；
  - 若目标在记忆中且可见但拒绝 → 小步接近 + 重新观测；
  - 若目标不在记忆中 → 回退基础策略/请求重试（不能凭空抓）。
- 结果校验：

```
e_i^out = || (c_i^{t+H} - c_i^t) - Δĉ_i ||
recover = 1[ e_i^out > τ_out ]
```

`τ_out` 同样在成功 chunk 上校准（按任务族）。超过阈值 → 重抓/重对齐/回退。

### 4.5 MCA：Map-Conditioned Action Expert

- 槽位 token：

```
T_i = MLP([ v_i ; c_i ; Σ_i ; role_i ; state_i ; rel_i ; afford_i ])
```

- 动作专家 cross-attend 到 `{T_i}`、语言 `u_l`、本体 `q_t`、接触相位 `z_t`；目标查询 `q*` 选出 `i*`；输出动作 chunk `a_{t:t+H}`。
- 辅助头：
  - 目标槽位分类 `L_target`；
  - 预期位移 `Δĉ_i`（`L_disp`）；
  - 成功概率 `L_succ`（可选）；
  - 接触相位/边界沿用 FACT-VLA。
- 训练损失：

```
L = L_flow
  + λ_t L_target
  + λ_d L_disp
  + λ_p L_proto
  + λ_c L_cons
  + λ_f L_phase
  + λ_g L_grasp
  + λ_r L_recover
```

- `L_target` 弱标签来自未来 EE 轨迹/未来放置点；`L_disp` 来自未来槽位质心差；`L_proto` 对比学习（同角色/同任务为正）；`L_cons` 跨视角/时序一致性；`L_phase/L_grasp` 沿用 FACT-VLA；`L_recover` 用扰动/失败恢复数据。
- 注入方式：冻结 backbone，训练 slot projection + action expert LoRA + 辅助头；显存不够时只训 projection/heads。
- 与 FACT-VLA 的优先级：
  - 地图验证失败 → 不进入接触段；先重定位；
  - 接触相位 P2/P3 → 地图仍校验目标槽位；若目标被换掉，立即退段；
  - 相位/地图冲突 → 安全优先（暂停/回退）。

### 4.6 与 FACT-VLA 的整合

- FACT-VLA 的贡献是“接触相位 + 夹爪滞止 + 柔顺运行时”，解决“插不准/抓不稳”；它不解决“对象是谁/在哪”。
- PROTO-MAP 的贡献是“对象恒存 + 校准验证”，解决“找错/忘记”；它不替代接触控制。
- 整合后：
  - **where/what**：地图选目标槽位、容器、放置点；
  - **how**：接触相位选接近/接触/插入/释放策略；
  - **whether**：CPV/OV 决定是否执行/恢复；
  - 三者共用一个 checkpoint，满足单模型。
- 训练顺序：先 FACT-VLA 接触（第 10 轮），再冻结/低学习率加地图头；避免地图头破坏已有接触行为。

### 4.7 运行时伪代码

```
M = empty_map(); z = init_phase()
for t in control_steps:
    obs = get_observation()
    if t % K_map == 0:                      # K_map=3~5 chunks
        P = stereo_depth(obs.I_L, obs.I_R)
        slots = slot_encoder(obs, P)
        M = match_update(M, slots)
        for s in M:
            s.r = nonconformity(s, P_task, M)
    valid = [s for s in M if s.r <= tau[s.task, s.role]]
    target = argmin_{s in valid} s.r
    if target is None:
        if M.has(last_target):
            scan_wrist(last_known=last_target.c)
        else:
            a = base_policy(obs)
        continue
    z = phase_head(obs, target)
    a = action_expert(obs, M, target, z)
    execute(a)
    M_next = update_map(obs_next)
    if outcome_error(M, M_next, target) > tau_out:
        recover(target)
```

- 频率：动作 10–30Hz；地图 2–5Hz；目标验证每 chunk；结果校验每 chunk。
- 延迟预算：双目 10–20ms、槽位 20–30ms、动作专家 40–80ms；总 p99 目标 <400ms 或比基础 VLA 增加 <80ms；超了就把地图降到 1–2Hz 或只验证目标槽位。
- 主动扫视：仅在验证失败时触发；小幅度、低速度、限时 1–2s；不改变任务语义。

### 4.8 复杂度与存储

| 模块 | 规模 | 运行时 |
|---|---|---|
| 双目深度 | 320×240，1/4 下采样 | 10–20ms GPU |
| 槽位编码器 | 12–16 slots，128 dim | 20–30ms |
| 原型库 | 32×4×16×128 ≈ 1MB | <2ms |
| 地图匹配 | O(K²)，K≤16 | <1ms |
| 动作专家 | LoRA/适配器 | 基础 VLA + 10–20% |
| 校准表 | 32×4 阈值 | 可忽略 |

## 5. 训练与数据引擎

### 5.1 数据切分

- 以 `episode_index` 为最小单位；禁止同一 episode 的帧跨 train/val。
- 背景/场景切分：用背景聚类或任务留出；若原始 metadata 有 session/recording 字段，优先 session-grouped。
- 任务留出：留出 4–6 个任务做 task-held-out 分析（不用于比赛训练，仅验证迁移）。
- 对象留出：在每个任务内留出 1–2 个物体实例（若可识别）做 unseen-object 代理。
- 扰动切分：合成扰动单独成 val/test，不混入 train；训练集可含扰动，但测试扰动类型要留出组合。

### 5.2 离线伪标签

- 性能轨道：SAM2（[S15]）+ DINOv2/CLIP（[S17][S18]）在采样帧上生成 mask/feature；1 帧/10；2–4k episodes；用于槽位/原型蒸馏。
- 合规轨道：Slot Attention（[S16]）或自监督对比学习，不依赖外部模型；指标可能低 3–5pp，但规则风险最小。
- 伪标签过滤：mask 面积/稳定性、跨帧一致性、深度合理性、与 EE 轨迹的接触一致性；低质量帧丢弃。
- 训练目标：mask/centroid/prototype/role；原型用 k-means/对比学习；不把伪标签当真值，只用一致性正则。

### 5.3 场景扰动引擎（SPE）

| 扰动 | 做法 | 校验 | 用途 |
|---|---|---|---|
| 背景替换 | 用其他 session/任务的桌面背景替换非对象区域；保持桌面平面/光照大致一致 | 对象 mask 完整、深度序合理 | 背景泛化 |
| 物体 relocation | 分割目标，移动到桌面自由位置；加阴影/边缘融合 | 不重叠、在桌面内、原型相似 | 位置泛化 |
| 干扰物插入 | 从其他任务插入 1–5 个物体，标为 distractor | 不与目标重叠、不遮挡关键接触点 | 干扰物泛化 |
| 遮挡 | 叠加手/物体 mask，遮挡 30–70% | 深度序/可见性合理 | 遮挡/对象恒存 |
| 人为干扰 | 在 chunk 间移动目标 3–15cm 或遮挡；生成新观测序列 | 轨迹连续、目标仍可找回 | 人为干扰/重定位 |
| 未见物品代理 | 留出物体实例或跨任务物体 | 语言/可供性仍可描述 | 未见物品 |

- **原型/几何校验**：每个合成样本过一遍槽位/深度/原型检查；不通过就丢弃。这是“prototype-validated augmentation”，不是随便贴图。
- 合成数据只用于训练/离线评测；不把合成成功率当真实成功率。
- 局限：没有真实物理/接触/光照；接触任务仍以真机/官方数据为主。

### 5.4 课程

1. **Stage A**：基础 VLA 在 33k 官方数据上微调（或加载已有 FACT-VLA 权重）；干净数据为主。
2. **Stage B**：冻结 backbone，训练槽位/原型/深度头；干净 + 轻扰动；离线地图指标。
3. **Stage C**：训练 MCA/辅助头；加入位置/干扰物/背景扰动；接触任务保持 FACT-VLA 相位损失。
4. **Stage D**：加入遮挡/人为干扰/双臂；训练结果校验与恢复。
5. **Stage E**：conformal 校准；不更新梯度。
6. **Stage F**：单任务 debug + 计分提交。

### 5.5 资源估算

| 项目 | 估算 |
|---|---|
| 基础 VLA 微调 | 6B + LoRA，8×H100 3–5 天；1–2×A100 则冻结 backbone 只训头 |
| 槽位/原型头 | 50–100M，1–2 GPU 天 |
| 伪标签 | 2–4k episodes × 1/10 帧；8 GPU 1–2 天（SAM2） |

- 策略：成功率、步骤分、目标选择准确率、重定位成功率、恢复率、恢复时间、抓错/掉落/碰撞、超时率。

- 比赛：单任务 debug 成功率、计分多任务平均成功率/步骤分、任务级胜负分布。

### 6.4 门控 G0–G5

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G-1 | 数据/任务名/切分是否干净 | canonical 映射 100%；无旧合集混入；episode 不跨 split | 停止训练，先修数据 |

| G2 | 场景切片是否真增益 | 位置/干扰/背景各 +5pp；未见 +3pp；人为恢复 +10pp；clean 回退 ≤1pp | 缩到多物体任务；减弱地图条件 |

### 6.5 统计功效

- 按 10 次/任务，32×10 的真机总分标准误约 2.6–2.8pp；单任务标准误约 15.8pp。**不要用单任务 +10pp 宣布全局胜利。**
- 判据：平均 +5pp 且 ≥60% 任务非负；或 8 个目标任务平均 +10pp 且 clean 不回退。
- 离线地图/原型指标样本量大，可设更严阈值；但要防止背景泄漏。
- 多次提交/多种子：若规则允许，重复 2–3 次；否则用任务级配对和效应量。

### 6.6 真机 debug 计划

- 任务选择（8 个，覆盖四族）：
  - 多物体/长程：ToolboxStorage、PackPhone、ArrangePlates、StorePaddle；
  - 双臂/可变形：FoldTowel、PackBag；
  - 接触：PlugInEthernet、Unlock。
- 每个任务 1–2 次；若 debug 次数有限，缩到 4 个任务×2 次：ToolboxStorage、ArrangePlates、FoldTowel、PlugInEthernet。
- 记录：成功率、失败模式（抓错/抓空/遮挡/超时/接触失败）、重定位次数、恢复时间、延迟。
- 判据：G4；不通过不烧计分。

| 8 | **EGP-D** debug 槽证据门控组合 | 提交稀缺；单任务 debug 不计分 | 用 debug 后验分配训练/提交；不是盲目整包 | 官网已支持 | 低 | G4 | debug 分布不同 |
| 9 | **FACT-VLA** 接触相位（保留） | 接触密集任务仍是硬骨头 | 相位/边界/滞止/柔顺；与地图互补 | 第 10 轮已设计 | 沿用 | G3/G4 | 接触代理噪声 |
| 10 | **DGS-32X** 接触 + 场景切片 | 总分掩盖 slice 失败 | 配对切片 + 门控；不是单一平均 | 离线 + debug 可做 | 中 | G2–G4 | 合成/真机 gap |

### 7.2 主推：PROTO-MAP（#1）

- **动机**：位置/干扰物/背景/人为干扰四类 shift 的共同底层是“对象身份与位置在时间上不一致”；当前 VLA 的隐状态没有显式对象槽位，长程/遮挡下容易丢。
- **与现有差异**：
  - vs MolmoAct2：它用场景级深度 token 做几何 grounding；我们用对象槽位 + 记忆 + 校准门，深度只是输入。
  - vs Wall-OSS-0.5：它自认单帧；我们显式维护跨帧对象状态。
  - vs DreamZero：它用 14B 视频 WAM 学动力学；我们用对象级位移 + 结果校验，成本低、可解释。
  - vs UniManip（[S14]）：它用外部 agentic 场景图 + 规划器；我们把槽位记忆内化到单 checkpoint，不做外部规划。
- **可行性**：双目数据已核实；槽位/原型头轻量；地图只在桌面、短 episode，不需要 SLAM；底座可用 WLA/Wall/MolmoAct2。
- **资源**：33k episodes；槽位头 1–2 GPU 天；底座 LoRA 8×H100 3–5 天；运行时单卡。
- **步骤**：G-1 数据映射 → G0 双目/槽位 → G1 原型 → G2 切片 → G3 运行时 → G4 debug → G5 合规。
- **风险**：双目 API 假设失败；地图漂移；槽位在遮挡下错配；延迟；原型在未见物品上失效。

### 7.3 主推：CPV（#2）

- **动机**：模型“看起来自信”不等于“目标选对”；干扰物/背景/未见物品下需要可校准的接受/拒绝，而不是 softmax。
- **与现有差异**：
  - vs 普通分类头：原型是角色/任务级、开放词汇，不是闭集类别；
  - vs PTA/ProtoTTA（[S21][S22]）：它们做测试时原型更新/熵最小化；我们用原型做**非一致性分数 + split conformal**，不更新参数，输出校准门；
  - vs conformal policy learning（[S20]）：它校准切换策略；我们校准对象角色验证与结果监测。
- **可行性**：校准集可从 held-out episode/合成扰动构造；阈值按任务族；计算几乎为零。
- **资源**：校准数据 + 分钟级计算；无需训练。
- **步骤**：G1 先离线 AUROC/误接受；再接入运行时；α 可调 0.05/0.10。
- **风险**：分布 shift 破坏 exchangeability；校准集小；原型塌缩；对未见物品过保守。缓解：Mondrian、任务族分层、语言/可供性后备、报告经验覆盖率而非宣称无条件保证。

### 7.4 主推：MCA + OV（#3/#4）

- **动机**：即使选对目标，执行一个 chunk 后也可能抓空/抓错/被人移动；需要对象级结果校验，而不是只看动作似然。
- **与现有差异**：
  - vs 语言条件 VLA：增加槽位 token、目标查询、预期位移；
  - vs 视频 WAM：不预测整帧，只预测对象质心/状态，成本低；
  - vs 纯开环 chunk：执行后校验，失败可恢复。
- **可行性**：未来质心差可从数据自动生成；辅助头轻量；与 FACT-VLA 相位头共享。
- **资源**：MCA LoRA/适配器 + 辅助头；1–2 GPU 天；运行时 +10–20%。
- **步骤**：B2→B3→B4 消融；G3 延迟/安全；G4 debug。
- **风险**：辅助损失干扰动作；位移标签在接触/可变形物体上噪声大；恢复动作可能碰撞。缓解：小权重、只在关键相位启用 OV、恢复动作限幅。

### 7.5 其余创新点（#5–#10）

- **SGM**：双目 + EE 锚点；比单目深度可靠；比 SLAM 轻。风险是 API 映射/标定；G0 一票否决。
- **SPE**：背景/位置/干扰物/遮挡/人为扰动；每个样本过原型/几何校验；只用于训练/离线评测。风险是合成不真实；以真机 debug 为准。
- **LAP**：语言/可供性后备；未见物品不靠闭集分类；用 VLA 内语言编码，不引入外部 VLM。
- **EGP-D**：8 任务×1–2 次 debug；Beta-Binomial 后验分配；成功率先行；不追榜。
- **FACT-VLA**：保留接触相位/滞止/柔顺；与地图互补；不重复第 10 轮细节。
- **DGS-32X**：接触 + 场景切片；配对比较；门控；避免总分掩盖失败。

### 7.6 剪枝清单

| 路线 | 剪枝理由 | 替代 |
|---|---|---|
| 完整 3D SLAM / NeRF / Gaussian | 桌面固定、短 episode；延迟/工程不划算 | 2.5D 对象槽位图 |
| 外部在线 VLM/LLM 规划 | 单模型合规、延迟、§6 可信度 | VLA 内语言 + 原型/可供性 |
| 完整视频 WAM（DreamZero 式） | 14B/7Hz；训练/推理重 | 对象级位移预测 + 结果校验 |
| 每任务分类器 | 未见物品失效 | 开放词汇原型 + 可供性 |
| 全库检索 33k episodes | 内存/延迟/场景 shift 检索错 | 紧凑原型库 + 槽位匹配 |
| 触觉/力闭环 | API/数据没有 | FACT-VLA 接触相位 |
| 纯图像增强 | 不真实、无对象身份 | 原型/几何校验的场景扰动 |
| 只换更大模型 | 前三在噪声内；边际收益低 | 结构化记忆 + 校准验证 |

## 8. 比赛策略

### 8.1 EGP-D：debug 槽的证据门控组合

- 家族：
  - F1 接触密集（HangCup、PlugCharger、PlugInEthernet、Unlock、SyringeWaterTransfer）；
  - F2 多物体分拣/整理（ColorArrangement、FruitSorting、ArrangePlates、StoreCups、OrganizeStationery、ToolboxStorage）；
  - F3 双臂/可变形（FoldTowel、PackDoll、PackBag、PlacePhotoFrame、RemovePinnedNote）；
  - F4 长程装箱/堆叠（PackPhone、StorePaddle、OrganizeTools、PaperCupStacking、StackBowls）。
- 先验：每族权重按任务数/难度；用 Beta-Binomial 后验更新；debug 结果只更新族级，不直接外推全局。
- 分配：高不确定性 × 高权重的族优先；每族至少 1 个 debug 任务；总 debug 8 任务×1–2 次。
- 决策：
  - 若 PROTO-MAP 在 F2/F3 明显增益、F1 不回归 → 提交地图版；
  - 若 F1 回归 → 对接触任务保留 FACT-VLA 路径/降低地图干预；
  - 若都不显著 → 回滚 known-good，省计分提交。

### 8.2 提交节奏

1. **安全版**：基础 VLA + FACT-VLA（known-good），先确认接口/延迟/稳定性。
2. **地图离线版**：G0/G1 过，但不提交计分；先单任务 debug。
3. **地图 debug 版**：G2/G3 过，8 任务 debug；G4 过。
4. **计分版**：只改一个变量（加地图/验证），便于归因；若回退 >2pp，回滚。
5. **冲分版**：在稳定版上加 SPE/LAP/OV 的组合；每次只加一组，保留回滚。

### 8.3 成功率先行

- 种子 JSON 中成功率与步骤分几乎同秩（Pearson 0.998；榜首 29.7/39.0，榜尾 20.5/28.1）；先把成功做上去。
- 步骤分只在成功平台期做保险；不要为了省时间牺牲成功。
- 单任务 debug 不计分，适合试错；计分提交稀缺，默认保守。

### 8.4 合规与可信度

- 单 checkpoint；不按任务切换权重；不把任务 ID 当隐式分支。
- 不调用外部在线模型；离线伪标签/分割是否允许按规则，默认自监督轨道。
- 报告延迟、失败模式、恢复行为；§6 可信度是评审维度，不是可选。
- 远程真机安全：动作限幅/低通/边界；扫视/恢复动作限时；异常立即回退。

## 9. 风险与开放问题

### 9.1 技术风险

| 风险 | 触发 | 缓解 |
|---|---|---|
| 双目 API 假设失败 | `cam_left_high/right_high` 不是同步双目 | G0 验证；回退单目/2D |
| 标定/同步误差 | 深度尺度错、重投影大 | EE/桌面锚点；在线标定；只用相对深度 |
| 地图漂移 | 长 episode、遮挡、重复纹理 | 桌面平面 + EE 锚点；短记忆；重定位 |
| 槽位错配 | 相似物体、遮挡 | 原型 + 关系 + 时序；连续 2 帧确认 |
| 原型失效 | 未见物品/背景 shift | 语言/可供性后备；低置信只做小步确认 |
| conformal 失效 | shift 破坏 exchangeability | Mondrian；经验覆盖率；不宣称无条件保证 |
| 结果校验噪声 | 接触/可变形物体位移难测 | 只在关键相位启用；多信号融合 |
| 延迟 | 每帧深度/槽位 | 降频；只验目标；1/4 分辨率 |
| 辅助损失干扰 | 地图头破坏动作 | 冻结 backbone；小权重；先 B1 后 B2 |
| 合成不真实 | SPE 伪影 | 原型/几何校验；真机 debug 为准 |

### 9.2 规则/工程风险

- 单模型/无外部在线模型：所有在线头必须在一个 checkpoint；离线工具要披露。
- 提交次数/截止未知：默认稀缺；先 known-good；不把所有预算押在一次大改。
- 远程 API 网络/端口：多端口共享模型时 per-port 状态隔离；token 每次返回；超时重试要幂等。
- 真机安全：恢复/扫视动作可能碰撞；限幅/限时/回退。
- 数据许可：官方数据只用于比赛；不混入外部数据。

### 9.3 评测风险

- 若按 10 次/任务，真机噪声大；单任务 debug 不能外推。
- 合成扰动与真机 shift 有 gap；离线增益不等于闭环增益。
- 排行榜种子不可信；不要用排名做模型选择。
- 任务名映射错误会导致训练/评测错位；G-1 必须过。

### 9.4 开放问题

1. `cam_left_high` / `cam_right_high` 是否同步双目？基线/标定/时间戳？
2. 规则正文的 trial 数、180s、5 轴×2、提交次数/截止？
3. 单任务 debug 能否选任务、次数、是否返回视频/日志、是否同分布？
4. 人为干扰的具体协议（何时、如何移动/遮挡）？
5. 未见物品集合是什么？是否跨任务/跨类别？
6. 辅助头/离线伪标签/外部工具是否允许？如何披露？
7. 深度/双目是否允许？是否有传感器限制？
8. 延迟的评审阈值/可信度标准？
9. 官方 33k 数据是否就是计分训练集？旧小合集是否仍被引用？
10. 多端口提交的端口数/并发限制？

## 12. 一句话押注

**在五类场景泛化轴上，最值得押注的不是再换一个更大的 VLA，而是给现有 VLA 加一张对象恒存的 2.5D 语义记忆，并用 conformal 原型校验决定“是否执行/何时重定位”；它与 FACT-VLA 的接触相位共用同一个 checkpoint，先解决“找错对象/忘记对象”，再解决“插不准”。**
