# 第 8 轮 · METRIC：成功率优先，步骤分只破同分

> 检索/复核日期：2026-10-26（UTC）。赛事身份确认不变：宇树科技 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「视觉-语言-动作模型（VLA）」「上下文理解」「评测指标」。我先用官方手册把排名与评测结构钉死，再合成主判断：**排行榜是成功率优先、步骤分仅破同分；每任务 10 次 = 5 个泛化轴 × 2；32×10=320 episodes 的统计噪声约 ±2.6pp。因此，最值得做的不是把 VLA 继续做大，也不是抠步骤分，而是做一个“成功率优先的测试时推理控制器”：用同一 checkpoint 的步级成功评论家预测每步成功/撤销风险，用轴感知上下文在 10 次运行内检索与自适应，用任务条件 MoE 在单模型内逼近 specialist。** 上一轮 PILOT-GPR 的“终局放置=步骤分大头”前提被官方规则推翻，必须修剪；放置仍然重要，但它是“成功率闸门”的一部分，不是步骤分套利。

## 0. 本轮先核实：六个事实

### 0.1 排名是 lexicographic：成功率优先，步骤分只破同分

官方中文手册原文（[S31]）：

> 实时榜单按32个任务的 **总平均成功率** 进行排序，成功率相同时按 **总平均步骤分** 排序，若仍相同，则提交日期较早的模型排序靠前。

英文手册同一句（[S32]）：

> The real-time leaderboard is sorted by overall average success rate across all 32 tasks. In the event of a tie, the overall average step score is used as the differentiator. If still tied, earlier submission dates rank higher.

这句话直接推翻了第 7 轮的核心前提。第 7 轮把“步骤分约 60% 权重大头”当作资源分配依据；实际规则里，**步骤分只在成功率完全相同时才起作用**。这不是“步骤分不重要”，而是“步骤分不是主目标”：它可以是训练信号、诊断信号、破同分保险，但不能拿来替代成功率做优化。

### 0.2 10 次运行 = 5 个泛化轴 × 2

官方规则（[S31][S32]）：每任务 10 次独立运行；5 种泛化类型各出现 2 次——位置、干扰物、桌面背景、未见物品、人为干扰；单次 180s，超时记失败；32 任务全部用同一模型，模型类型不限（World Model、VLA 均可）。

这给出三个设计约束：

- 每个轴在每任务里只占 2 次，轴级估计非常 noisy；不要按单轴 1-2pp 的差异做决策。
- 轴是**已知的、离散的、每任务固定的**，模型可以在线推断“当前是哪一轴”，并调用对应策略/记忆。
- 10 次是同一任务内的重复，天然形成“学习曲线”；是否允许跨 episode 记忆是合规开放问题，但技术上 `reset()` 只清 episode 内状态。

### 0.3 榜单仍是占位，不能当真实排名

`leaderboard.html` 仍是「即将发布 / Coming Soon」；`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，发布时间 2026-10-08，8 个模型 × 32 任务 = 256 条 task_metrics（[S56]）。榜首 MolmoAct2/DexHacker 的成功率 29.7%、步骤分 39.0；最低 GR00T N1.5 20.5%/28.1%；8 个模型平均“步骤分 − 成功率” = **+8.59pp**。

这些数字只能当“难度先验”和“失败集中在中后段”的弱证据，不能用来判断谁强谁弱。用户提到的“榜首不到 30%”正好对应占位榜首 29.7%，必须标注“占位”。

### 0.4 数据与接口：33k 真机演示，但没有 step 标签

- HF collection `unibot-v1-challenge-dataset`：32 个数据集，约 33k episodes / 169h；每任务约 1k 条；四路相机 `head_stereo_left/right` + `wrist_left/right`；EE 位姿在 base 与 torso 两套坐标；**没有 step/subtask 标签**（[S3][S55]）。
- 提交 API v2（2026-08-21）：`metadata` 支持 `control_space`（joint/ee）、`obs_delta_indices`、`image_resize`、`action_chunk_size`；观测含四路 RGB、双臂关节/EE、夹爪、`lower_body[15]`、`language` 单字符串；`reset()` 每 episode 一次；N 台机器人随机顺序、N 个连续端口从 8765（[S54]）。
- 训练集里的 `state_torso`、`state_d435`、torso-frame EE 位姿等字段，评测 API 不发送；训练时必须丢弃或重建，不能假设线上有。
- 相机键映射：`head_stereo_left/right → cam_left_high/right_high`；`wrist_left/right → cam_left_wrist/right_wrist`。

### 0.5 官方基线：UnifoLM-VLA-0 是 8B、非商用许可；WALL-OSS-0.5 是 4B、Apache-2.0

- **UnifoLM-VLA-0**：8B，2026-01-29 发布，CC BY-NC-SA 4.0，12 类 G1 任务、单一策略（[S40]）。
- **UnifoLM-WMA-0**：world-model-action 基线，许可/版本以模型卡为准（提交前复核）。
- **WALL-OSS-0.5**：4B（3B VLM + action 组件），20+ embodiments，1M+ trajectories/epoch，微调后 15 个真机任务平均 task progress 60.5%，比 π0.5 高 17.5pp（[S34]）。
- **MolmoAct2**：5.5B，LIBERO 97.2%、RoboEval 44.3%、真机 8 任务 50.1%（[S33]）。
- **Spirit-v1.5**：Qwen3-VL-4B + DiT action head（[S37]）。
- **GigaBrain-0**：world-model 生成数据 + RGBD + embodied CoT（[S38]）。
- **DM0**：2B 级（模型卡 2.4B），Table30 specialist 62.0%、generalist 37.3%（[S36]）。
- **DreamZero**：14B WAM，7Hz 闭环，新任务/新环境泛化 >2×（[S35]）。

### 0.6 外部校准：Table30 V2 的 generalist 天花板约 43%

RoboChallenge Table30 V2（30 任务、1080 runs、32,980 episodes、57 models）榜首 LoopWAM 43.33%，VLA-DM0.5 40.67%，ambase 31.67%（[S39]）。这说明：**在真实桌面多任务泛化评测里，通才模型的成功率天花板仍然不高**；specialist 可以到 62%（DM0），但 generalist 只有 37.3%。UniBot 的占位榜首 29.7% 低于 Table30 V2 通才榜首 43.33%，但都远低于 specialist 62%；通才成功率天花板不高，不是“换个更大模型”就能解决。

## 1. 三个灵感词，各自钉到事实上

### 1.1 VLA：头部模型已经很强，但“强”没有转化成成功率

把 0.5 的数字放在一起看，会发现一个刺眼的事实（跨 benchmark 对照，不是同一评测）：

| 模型 | 公开强项 | UniBot 占位 SR |
|---|---|---:|
| MolmoAct2 | LIBERO 97.2、RoboEval 44.3、真机 50.1 | 29.7 |
| WALL-OSS-0.5 | 60.5% task progress、20+ embodiments | 28.5 |
| DreamZero | 14B WAM、2× generalization、7Hz | 27.9 |
| Spirit-v1.5 | Table30 SoTA（2026-01） | 25.9 |
| DM0 | Table30 specialist 62.0 | 23.5 |
| π0.5 | 强开放世界泛化 | 22.8 |
| GigaBrain-0 | world-model 数据、RGBD、CoT | 22.6 |
| GR00T N1.5 | NVIDIA 人形基础模型 | 20.5 |

这不是说这些模型“只有 20-30% 的能力”，而是说：**在 32 任务、5 轴、180s、单模型的评测协议下，公开 benchmark 的强项没有直接转化为 episode-level success**。可能的原因：

- 公开 benchmark 多是单任务/短程/实验室；UniBot 是长程、多任务、OOD、真机。
- progress 指标会奖励“做了大部分步骤”，但成功率要求“全部步骤完成”；WALL-OSS-0.5 的 60.5% progress 与 28.5% 占位 SR 的落差就是“metric trap”。
- 模型越大，延迟/部署/闭环稳定性越难；14B WAM 的 7Hz 在 180s 内要完成多步任务，时间预算并不宽裕。

结论：**VLA 是底座，不是差异化来源**。真正的差异化在“如何用这个底座去最大化成功率”。

### 1.2 上下文理解：不只是语言，而是“轴 + 步 + 历史”

UniBot 的“上下文”至少有四层：

1. **语言上下文**：32 任务 × 5 条英文复述（数据集 `tasks.parquet` 里用 `@` 分隔；[S5]），评测可能采样其中一条。
2. **任务上下文**：官方 `info.json` 给出每任务的评分步骤与权重（第 7 轮已抓全 32 个；[S2]），这是天然的 step graph。
3. **评测上下文**：当前是 5 个泛化轴中的哪一个？位置偏移、干扰物、背景替换、未见物品、人为干扰——它们的视觉/动力学特征不同，最优策略也不同。
4. **历史上下文**：同一任务已经跑了第几次？之前哪一步失败？哪些动作被证明有效？10 次运行天然提供跨 episode 的经验。

现有 VLA 大多只显式使用第 1 层（语言）和第 2 层的一部分（任务 ID）；第 3、4 层几乎空白。**“轴感知 + 步级状态 + 成功记忆”是上下文理解在评测协议下的具体化**，也是本轮想押注的新角度。

### 1.3 评测指标：成功率是乘积，步骤分是加权和

设任务 t 有 K_t 个步骤，p_{t,i} 是在前 i-1 步都成功的条件下第 i 步成功的概率，则：

```text
SR_t = ∏_{i=1}^{K_t} p_{t,i}
SS_t = Σ_{i=1}^{K_t} w_{t,i} · P(step i completed),  Σ w_{t,i} = 100
Overall SR = (1/32) Σ_t SR_t
Overall SS = (1/32) Σ_t SS_t
Rank: max SR; tie → max SS; tie → earlier submission
```

对 p_{t,i} 求偏导：

```text
∂SR_t/∂p_{t,i} = ∏_{j≠i} p_{t,j} = SR_t / p_{t,i}
```

这个式子说明：

- **瓶颈步（p 最小）的边际收益最大**；步骤权重 w_{t,i} 完全不进入成功率。
- 如果某任务 3 步、p=(0.9, 0.9, 0.5)，SR=40.5%；把瓶颈 0.5→0.6，SR=48.6%（+8.1pp）；把非瓶颈 0.9→1.0，SR=45.0%（+4.5pp）。瓶颈的杠杆接近 2 倍。
- 步骤分是“加权和”，优化它可能鼓励“早停保分”（例如做到 70% 就停，避免失败后步骤分回退），这与成功率目标冲突。**所以步骤分只能当 tiebreak/诊断，不能当主目标。**

## 2. 统计功效：320 episodes 能分辨多大的提升？

每任务 10 次，32 任务 → 320 episodes。总体成功率是 32 个任务均值的宏平均。若各任务 p_t≈0.3，则：

```text
Var(SR) = (1/32²) Σ_t p_t(1-p_t)/10
        ≈ (1/1024) × 32 × 0.021 = 0.000656
SE(SR) ≈ 2.56pp
```

这意味着：

- **1-2pp 的提升在 320 episodes 下基本不可分辨**；不要为这种量级的改动做重大架构决策。
- **≥5pp 的真实提升**才约 2 SE，值得作为目标；≥8pp 更稳。
- 评估必须用**配对 bootstrap**（同一任务/轴/种子配对）或 **SAVI 序贯检验**（[S43]），否则会被任务难度差异淹没。
- 10 次/任务也意味着**单任务的成功率分辨率只有 10%**；不要用单任务 1-2 次成功差异判断方法好坏。

这条统计约束会直接改变研究策略：**只做效应量大的干预**（瓶颈步、轴级失败、可恢复失败），不做“再多训一点”的小修小补。

## 3. 主判断：从“预测动作”转向“最大化成功率”

### 3.1 失败模型：成功率低，通常不是“每一步都差”，而是“某一步特别差 + 失败后不恢复”

把成功率写成乘积后，最值得问的问题是：**每个任务的瓶颈步是哪一步？p 是多少？失败后能不能恢复？**

以占位榜的步骤分-成功率差（+8.59pp）为弱先验：多数失败不是“第一步就抓不到”，而是“做到中后段、倒在某个关键步”。第 7 轮已抓的 32 个 `score_steps` 给出了每步权重，但权重不等于瓶颈；我们需要用**步骤级条件成功率**（step-level conditional success matrix）从真实/仿真 rollout 中估计 p_{t,i}，而不是用权重猜。

### 3.2 三个机制：成功评论家、轴感知记忆、任务条件 MoE

**机制 A：步级成功评论家（PWM, Progress/Outcome World Model）**

- 在同一 checkpoint 上加多个 head：`p(step i 成功)`、`p(整任务成功)`、`p(step i 被撤销)`、`p(当前轴)`、`p(当前步)`。
- 用反事实失败数据训练：位置扰动、干扰物、背景替换、未见物品、人为干扰（官方 human 备注是现成剧本）、动作噪声、过早释放、碰撞。
- 推理时对 N 个候选 action chunk 打分，选“期望整任务成功率”最高的，而不是选“动作似然”最高的。
- 关键：**步级 + 撤销感知**，不是终端成功分类器；它要知道“这一步做完会不会被下一步/人撤掉”。

**机制 B：轴感知测试时记忆（CESM, Cross-Episode Success Memory）**

- 每个 episode 结束后，把成功的 observation-action 段按 `(task, step, axis, key)` 存入长期记忆；失败段只存“诊断标签”，不存动作。
- 下一次同任务运行时，先推断当前轴，再检索**同轴/轴不变**的成功段，作为 flow-matching 的先验（Retrieve-then-Steer 式，[S45]）。
- 这不是“多模型”：记忆是数据，策略仍是同一个 checkpoint；也不是“偷看测试集”：只用模型自己在评测中产生的成功经验。
- **合规定位**：规则说 10 次“独立运行”，跨 episode 记忆可能被解释为不允许；因此默认 OFF，做成一个开关；主方法不依赖它也能工作（见机制 A/C）。若评测服务在任务间重启，记忆自然失效，方法退化为 within-episode 版本。

**机制 C：任务条件 MoE（TC-MoE）**

- 单 checkpoint 内 6-8 个 skill experts：抓取、放置、插入、关节物体、可变形物体、工具使用、长程恢复。
- Router 以 task card（任务/步骤/物体/轴）为条件；训练时 context dropout，防止 router 过拟合任务 ID。
- 动机：DM0 的 specialist 62.0% vs generalist 37.3%（[S36]）说明“一个稠密通才”离“专家”很远；MoE 是在**单模型规则内**逼近 specialist 的最直接结构。
- 关键：不是 per-task LoRA（那是 32 个模型，违反精神且不泛化），而是**按技能分组**的专家，跨任务共享。

### 3.3 控制器：把测试时算力花在瓶颈步上

给定 step graph 和每步的成功概率估计，控制器做一个小的动态规划：

```text
V_i(s) = max_{a ∈ candidates} [ p_i(a) · V_{i+1}(s') + (1-p_i(a)) · R_i(s) ]
```

其中 `R_i(s)` 是重试/恢复的价值，`p_i(a)` 是 PWM 对候选动作的步级成功预测。这样：

- 在瓶颈步生成更多候选（N 大）、允许更多重试；
- 在低风险步快速通过，节省 180s；
- 检测到 undo（p 从 1→0）时回退到上一步，而不是继续执行错误计划；
- 时间预算管理器保证长程任务不会在最后一步超时。

### 3.4 为什么这比“继续做大 VLA”更划算

- 头部模型的公开强项与 UniBot 成功率脱节（§1.1），说明瓶颈不在语言/语义，而在**执行可靠性 + OOD 恢复 + 指标对齐**。
- 成功评论家/控制器是**模型无关的**：可以挂在 WALL-OSS-0.5、UnifoLM-VLA-0、MolmoAct2 上；底座 bake-off 不影响方法。
- 轴感知记忆和 TC-MoE 都是**单模型合规**的；不需要外部数据也能起步（反事实失败可从官方演示合成）。
- 统计上，瓶颈步 + 恢复的效应量通常 >5pp，符合 320 episodes 的可分辨门槛。

## 5. 风险与合规（先立后破）

- **跨 episode 记忆**：规则写“10 次独立运行”，可能禁止跨 run 共享状态；默认 OFF，开关化；主方法（PWM + 控制器 + TC-MoE）不依赖它。
- **评论家校准**：OOD 轴上的 p 估计可能过自信；用温度缩放/conformal/保守回退；只用它做候选排序，不做绝对阈值。
- **延迟**：best-of-N + 多 head 会增加推理时间；目标 `get_action` p99 <100ms；N 自适应（瓶颈步 4-8，普通步 1-2）；批量生成。
- **外部数据**：官方手册 2.2 之后被截断，外部数据/预训练权重是否允许未确认；默认只用官方 33k + 合成反事实；外部数据开关默认 OFF。
- **单模型审计**：所有学习组件必须在同一 checkpoint；记忆是数据；控制器是确定性代码；模型卡写清。
- **统计噪声**：320 episodes SE≈2.56pp；只追 ≥5pp 效应；配对 bootstrap/SAVI；不因 1-2pp 波动改方案。
- **规则截断**：飞书手册后半部分（外部数据、算力、提交配额、评分细节、赛程）未读全；提交前必须邮件/人工确认。

## 6. 一句话押注

**把排行榜的 lexicographic 结构当第一性：成功率优先、步骤分只破同分；用同一 checkpoint 的“步级成功评论家 + 轴感知上下文 + 任务条件 MoE”做测试时推理控制，把算力集中在瓶颈步和可恢复失败上——这是本轮最值得押注的方向。**

# 第 8 轮产物区 · METRIC-VLA 技术报告（成功率优先 + 轴感知上下文 + 测试时成功估计）

> 目标赛事：宇树科技 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署、官方远程真机 API 评测。检索/复核日期：**2026-10-26（UTC）**。本报告在第 7 轮 PILOT-GPR 的基础上做“指标纠偏”：官方排行榜是**成功率优先、步骤分仅破同分**，第 7 轮的“步骤分大头”前提不成立。报告的核心不是再提出一个更大的 VLA，而是把**评测协议**当作第一性设计对象，提出 METRIC-VLA：一个成功率优先的测试时推理控制器。

---

## 0. 产物摘要

### 0.1 一句话

**UniBot 的排名是 lexicographic：先比 32 任务总平均成功率，成功率相同才比步骤分；每任务 10 次 = 5 个泛化轴 × 2，320 episodes 的 SE≈2.56pp。因此，最高杠杆不是把 VLA 做大或抠步骤分，而是用同一 checkpoint 的“步级成功评论家（PWM）+ 轴感知上下文（axis posterior + CESM）+ 任务条件 MoE（TC-MoE）”做测试时推理控制，把算力集中在瓶颈步和可恢复失败上。**

### 0.2 组件与是否进推理

| 组件 | 作用 | 进推理？ |
|---|---|---|
| TC-MoE VLA 主干 | 单 checkpoint、6-8 个技能专家、任务/步骤条件路由 | 是（唯一学习模型） |
| PWM 成功评论家 | 步级成功、整任务成功、撤销风险、轴后验、步状态 | 是（同一 checkpoint 多 head） |
| Axis posterior | 推断当前泛化轴（位置/干扰物/背景/未见/人干扰） | 是（head + 规则先验） |
| CESM 跨 episode 成功记忆 | 存成功段、按轴/步检索、flow-matching 先验 | 可选（默认 OFF，合规开关） |
| Success-first controller | 候选生成、DP 分配算力、best-of-N、重试/回退 | 是（确定性代码） |
| Soft chunk truncation | 允许相位级早重规划，剩余 chunk 填 hold | 是（控制代码） |
| Time budget manager | 180s 预算、瓶颈步预留、长程任务限重试 | 是（控制代码） |
| Counterfactual failure engine | 位置/干扰/背景/未见/人干扰/动作噪声 | 否（训练数据） |
| Metric harness | 排名模拟、配对 bootstrap、SAVI、功效分析 | 否（评测流程） |
| Compliance compiler | 单模型审计、数据开关、模型卡 | 否（流程） |

### 0.3 预期收益（可证伪）

- 若瓶颈步的条件成功率从 p 提升到 p+Δ，任务成功率提升 ≈ Δ × ∏_{j≠i} p_j；对 3 步任务、其他步 0.8-0.9，乘数约 0.6-0.8。**瓶颈步 +10pp ⇒ 任务 SR +6-8pp**。
- 目标：整体 SR +5pp 以上（320 episodes 下约 2 SE），保守 +3pp；若只做到 +1-2pp，视为噪声，不换方案。
- 可证伪点：若离线步骤级诊断显示瓶颈步不明确（各步 p 接近），或 PWM 的候选排序准确率 <60%，则“瓶颈步优先”假设不成立，回退到纯 TC-MoE + 基础控制器。

### 0.4 与上一轮（PILOT-GPR）的关系

| 关系 | 内容 |
|---|---|
| 保留 | WALL-OSS-0.5/UnifoLM-VLA-0 底座、TLE 步骤切分、ACP/GF 反事实、检索式上下文、放置/恢复、统计评测 |
| 升级 | 终局放置 → 瓶颈步成功；步骤分大头 → 步骤分仅 tiebreak；per-task LoRA → TC-MoE；跨 episode 记忆 → 合规开关 |
| 新增 | PWM 步级成功/撤销评论家、轴后验、CESM、success-first controller、soft chunk truncation、metric harness、compliance compiler |
| 修剪 | 步骤分优先、terminal-only、optimal stopping 保步骤分、14B WAM 主底座、外部数据主路径、全 32 任务高保真孪生、每任务 LoRA |

## 1. 事实核对（本轮新增，全部一手；来源表见 §13）

### 1.1 排名规则：成功率优先，步骤分只破同分

官方中文手册（[S31]）原文：

> 实时榜单按32个任务的 **总平均成功率** 进行排序，成功率相同时按 **总平均步骤分** 排序，若仍相同，则提交日期较早的模型排序靠前。

英文手册（[S32]）同一句：

> The real-time leaderboard is sorted by overall average success rate across all 32 tasks. In the event of a tie, the overall average step score is used as the differentiator. If still tied, earlier submission dates rank higher.

**结论**：第 7 轮把“步骤分约 60% 权重”当作资源分配依据是错误的；步骤分只在 SR 完全相同时才影响排名。步骤分仍可作为训练信号/诊断信号/破同分保险，但不能替代 SR 作为主目标。

### 1.2 每任务 10 次 = 5 个泛化轴 × 2

官方规则（[S31][S32]）：

- 通才赛道：单模型完成全部 32 任务；每任务 10 次测试；计算每任务平均成功率、平均过程分，计入排行榜。
- 10 次运行包含 5 种泛化类型，每种各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
- 单次真机执行最大 180s，超时记失败，并按执行情况计算步骤分。
- 模型类型不限（World Model、VLA 均可），但必须单模型，不得混合多个模型。

## 2. 指标算术：为什么成功率优先会改变一切

### 2.1 三个公式

```text
SR_t = ∏_{i=1}^{K_t} p_{t,i}
SS_t = Σ_{i=1}^{K_t} w_{t,i} · P(step i completed)
Rank: max (1/32)Σ_t SR_t; tie → max (1/32)Σ_t SS_t; tie → earlier date
```

### 2.2 瓶颈步的边际收益

```text
∂SR_t/∂p_{t,i} = SR_t / p_{t,i} = ∏_{j≠i} p_{t,j}
```

例子（3 步任务）：

| 情形 | p1 | p2 | p3 | SR | 改动 | ΔSR |
|---|---:|---:|---:|---:|---|---:|
| 基准 | 0.90 | 0.90 | 0.50 | 40.5% | — | — |
| 瓶颈 +0.10 | 0.90 | 0.90 | 0.60 | 48.6% | p3 0.5→0.6 | **+8.1pp** |
| 非瓶颈 +0.10 | 1.00 | 0.90 | 0.50 | 45.0% | p1 0.9→1.0 | +4.5pp |
| 全部 +0.05 | 0.95 | 0.95 | 0.55 | 49.6% | 三步都改 | +9.1pp |

结论：**瓶颈步的每单位提升约等于非瓶颈步的 1.8 倍**（在这个例子里）；如果瓶颈更低（0.3），杠杆更大。

### 2.3 统计功效

```text
每任务 10 次，32 任务 → 320 episodes
p≈0.3 时，SE(总体 SR) ≈ 2.56pp
95% CI 半宽 ≈ 5.0pp
```

因此：

- **+1-2pp 不可分辨**；+3pp 约 1.2 SE；+5pp 约 2 SE；+8pp 约 3 SE。
- 目标设为 **+5pp 真增益**；低于 +3pp 的离线提升不进入真机验证。
- 用配对 bootstrap（同任务/轴/种子）降低方差；用 SAVI 序贯检验（[S43]）在证据足够时早停，节省真机预算。
- 不要用单任务 1-2 次成功差异做模型选择；单任务 10 次的成功率分辨率只有 10%。

### 2.4 轴分解

```text
Overall SR = (1/5) Σ_a SR_a
SR_a = (1/32) Σ_t SR_{t,a}
```

每轴每任务只有 2 次运行，轴级估计的 SE 更大（p=0.3 时，单任务单轴 SE≈32pp；32 任务平均后≈5.7pp）。所以：

- 轴级结论必须跨任务聚合；
- 轴感知方法的收益要 >5pp 才能可靠；
- 不要为单个任务的单轴失败过拟合。

### 2.5 10 次运行的学习曲线（CESM 的数学）

若第 1 次成功率 p0，之后每次失败后记忆带来 δ 的增量，则 10 次平均最多提升约：

```text
δ × (1-p0) × (0+1+...+9)/10 = δ × (1-p0) × 4.5
```

p0=0.3、δ=0.05 时上界约 **15.8pp**；实际远低。这个上界说明记忆有潜力，但也高度依赖合规性和轴变化速度。因此 CESM 只做可选开关，不作为主方法的唯一支柱。

### 2.6 方法设计含义

| 应该优化 | 不应该优化 |
|---|---|
| 瓶颈步条件成功率 | 步骤权重/步骤分（除非破同分） |
| 整任务成功率（乘积） | 单步动作似然 |
| 轴级最弱失败模式 | 单任务单轴的 1-2pp 波动 |
| 可恢复失败（undo/retry） | “做到 70% 就停”的 partial score |
| 320 episodes 下 ≥5pp 的效应 | 1-2pp 的“改进” |

## 3. 头部模型分析：为什么需要“成功评论家”这一层

### 3.1 公开强项与 UniBot 成功率的脱节

| 模型 | 公开强项（不同 benchmark） | UniBot 占位 SR |
|---|---|---:|
| MolmoAct2 | LIBERO 97.2、RoboEval 44.3、真机 50.1 | 29.7 |
| WALL-OSS-0.5 | 60.5% task progress、20+ embodiments | 28.5 |
| DreamZero | 14B WAM、2× generalization、7Hz | 27.9 |
| Spirit-v1.5 | Table30 SoTA（2026-01） | 25.9 |
| DM0 | Table30 specialist 62.0、generalist 37.3 | 23.5 |
| π0.5 | 强开放世界泛化 | 22.8 |
| GigaBrain-0 | world-model 数据、RGBD、CoT | 22.6 |
| GR00T N1.5 | NVIDIA 人形基础模型 | 20.5 |

**解释**：

1. benchmark 的任务分布/时域/embodiment 与 UniBot 不同；
2. progress/partial credit 与 success 的度量不同；
3. 大模型在 180s 内的闭环稳定性/延迟/恢复能力未必更好；
4. 没有模型显式优化“episode-level success under 5-axis OOD”。

### 3.2 通才-专家 gap

DM0 的数据（[S36]）：specialist 62.0% vs generalist 37.3%，gap 24.7pp。Table30 V2 的 generalist 榜首 43.33%（[S39]）。这说明：

- 单模型通才的天花板远低于 specialist；
- UniBot 要求单模型 + 全 32 任务，不能走 per-task specialist；
- **在单 checkpoint 内做技能条件化（TC-MoE）** 是缩小 gap 的合理路径；
- 但 MoE 不是万能：如果 router 只学会任务 ID，OOD 轴会崩；需要 context dropout + 轴条件。

### 3.3 metric trap

WALL-OSS-0.5 的 60.5% task progress 与 UniBot 占位 28.5% SR 是最清楚的例子（跨 benchmark 对照）：**progress 高不代表 success 高**。原因：

- progress 可以在失败前达到很高（例如 80%），但 success 要求 100%；
- 评测的步骤分是“过程分”，不是“成功分”；
- 如果团队按 progress 调模型，会在瓶颈步之前过度优化，忽略最后的成功闸门。

### 3.4 缺失的一层：成功评论家/控制器

现有 VLA 的输出是 action chunk，训练目标是 action likelihood/flow matching；没有显式的“这个动作会不会让整个 episode 成功”的预测。METRIC-VLA 补上这一层：

- 步级成功评论家（PWM）预测 p(step success)、p(episode success)、p(undo)；
- 控制器用这些预测做候选选择/重试/回退；
- 这样就把“动作生成”变成“成功率最大化”的推理问题。

### 3.5 底座选择

| 底座 | 优势 | 风险 | 建议 |
|---|---|---|---|
| WALL-OSS-0.5 4B | Apache-2.0、action expert、20+ embodiments、部署便宜 | 需要确认 UniBot 相机/动作空间适配 | **默认** |
| UnifoLM-VLA-0 8B | 官方基线、G1 数据、单策略 12 任务 | CC BY-NC-SA（非商用）、8B 延迟 | 基线复现/备选 |
| MolmoAct2 5.5B | 强 sim/real、开源 | 需确认 license/动作空间 | bake-off |
| Spirit-v1.5 4B | Qwen3-VL + DiT、开放 | 需确认 license/动作空间 | bake-off |
| DreamZero 14B | 泛化强 | 14B 延迟/显存/部署 | 不作主底座 |

**策略**：先做 1-2 周 bake-off（相同数据/评测协议），选一个底座；方法层（PWM/控制器/MoE）与底座解耦。

## 4. METRIC-VLA 架构

### 4.1 总览

```text
┌──────────────────────── Offline（训练/标定）─────────────────────────┐
│ 官方 33k（LeRobot v3，四路相机，EE base 位姿，5 复述）                  │
│   ├─ TLE：步骤相位切分 + 接触/谓词标签 + 步骤级成功统计                 │
│   ├─ CFE：反事实失败引擎（位置/干扰/背景/未见/人干扰/动作噪声）         │
│   ├─ Axis labels：5 轴标签 + 轴不变键                                  │
│   └─ PWM 训练：步级成功/整任务成功/undo/轴/步状态                       │
└──────────────────────────────────────────────────────────────────────┘
                                   │
┌──────────────────────── Inference（单 checkpoint）────────────────────┐

│        │                           │                                  │
│        ▼                           ▼                                  │

```

### 4.2 输入与上下文 token

- **语言**：官方指令（32×5 复述之一）+ 中文映射；训练时做复述增强。
- **Task card**：任务 ID、步骤图（来自 `info.json` 的 `score_steps`）、步骤文本、权重（仅诊断）、物体列表、轴先验（官方 generalization 备注）。
- **Step state**：当前步索引、上一步完成/失败、已用时间、重试次数。
- **Axis posterior**：5 轴概率 + 证据（背景变化、物体位置、未见外观、人手出现）。
- **Memory summary**：最近成功/失败段的压缩 token（可选；默认无）。
- **Retrieved context**：同任务/同步骤/同轴的成功段（K=2-4），独立编码后注入。

### 4.3 TC-MoE 主干

- 6-8 个技能专家：`pick`, `place`, `insert`, `articulate`, `deformable`, `tool-use`, `long-horizon`, `recovery`。
- Router 输入：task card + step state + axis posterior + pooled visual/proprio features。
- 专家可以是 LoRA/FFN 级，不必复制整个 VLM；总参数控制在 4-8B。
- 训练：load balancing loss + context dropout（随机丢弃 task ID/axis，防止 router 只记任务）。
- 推理：top-2 routing；瓶颈步可启用更多专家/候选。

### 4.4 PWM 多 head

| Head | 输出 | 训练标签 | 用途 |
|---|---|---|---|
| Step success | p(step i 在 H 步内完成) | TLE 相位/谓词 | 候选排序、重试 |
| Episode success | p(整任务成功) | episode 成功/失败 | 候选排序、早停 |
| Undo risk | p(step i 被撤销) | 人干扰/回退段 | 监控、回退 |
| Axis | 5 轴 posterior | 评测轴标签/合成轴 | 记忆检索、策略调制 |
| Step state | 当前步索引/完成度 | TLE 相位 | step graph 同步 |

**校准**：温度缩放 + conformal prediction；在 OOD 轴上用保守阈值；若 PWM 不确定（熵高），回退到 base policy 的候选。

### 4.5 Success-first controller

```python
def act(obs, task_card, step, budget):
    axis = axis_head(obs, task_card)
    ctx = cesm.retrieve(task_card, step, axis) if memory_on else None
    candidates = vla.sample(obs, task_card, step, axis, ctx, n=N(step))
    scores = [pwm.score(c, obs, step) for c in candidates]
    best = argmax(scores, key=lambda s: s.p_step * s.p_episode * (1 - s.p_undo))
    execute(best, truncate=soft_truncate(step, best))
    if pwm.undo_detected(obs, step):
        step = step - 1
        retry_with_alternative()
    if pwm.step_success(obs, step):
        step = step + 1
    return step
```

**DP 分配**：对每个步骤估计 `V_i`，在瓶颈步增加 N/重试；在低风险步 N=1-2。时间预算：

```text
remaining = 180s - elapsed
reserve = Σ_{j>i} expected_time_j + safety
N_i = clamp(floor((remaining - reserve) / chunk_time), 1, N_max)
```

### 4.6 CESM（可选）

- **写入**：episode 成功后，按 `(task, step, axis)` 存 progress-calibrated 的 observation-action 段；失败 episode 只存诊断标签（不存动作）。
- **检索**：同 task/step/axis 优先；轴未知时用轴不变键（物体相对位姿、EE 速度、光流）。
- **注入**：flow-matching 中间步的 elite prior + confidence-adaptive guidance（Retrieve-then-Steer 式，[S45]）。
- **淘汰**：容量上限、时间衰减、冲突检测（动作一致性）。
- **合规开关**：默认 OFF；若规则禁止跨 episode 状态，则关闭；关闭后方法退化为 PWM + controller + TC-MoE。

### 4.7 Soft chunk truncation

API 的 `action_chunk_size` 固定，但任务相位可能提前完成/失败。做法：

- 执行 chunk 的前 `k` 步；若 PWM 检测到步完成/undo，提前 replan；
- 剩余 `chunk_size - k` 步填 `hold`（当前关节/EE 位姿）或安全回退动作；
- 这样既遵守 chunk 接口，又允许相位级早停；避免“执行完整 chunk 导致过冲/撞桌”。

### 4.8 单模型合规

- 所有学习组件（VLA、PWM heads、axis head、router）在**同一 checkpoint**；不是多模型集成。
- CESM 是数据，不是模型；controller 是确定性代码；不调用外部 API/模型。
- 模型卡写明：单 checkpoint、head 列表、记忆开关、外部数据开关、推理图。
- Compliance compiler：启动时扫描 import/网络调用/权重文件，生成审计报告；禁止 per-task 权重切换。

## 5. 数据引擎

### 5.1 官方数据与标签

- 33k 官方演示，全部成功；无 step 标签。
- TLE：用视觉/本体信号做相位切分（抓取、移动、放置、闭合、插入），并用接触/夹爪事件做谓词标签；人工抽检 10%。
- 步骤级成功统计：从 TLE 标签估计每个任务的 p_{t,i}；用 held-out 任务/轴校准。
- 5 条复述：训练时随机采样；指令匹配用规范化 + 嵌入兜底。

### 5.2 反事实失败引擎（CFE）

| 失败类型 | 生成方式 | 对应轴 |
|---|---|---|
| 位置偏移 | 物体/目标平移/旋转 | 位置 |
| 干扰物 | 在桌面/路径旁插入无关物体 | 干扰物 |
| 背景替换 | 换桌布颜色/纹理（2.5D 编辑） | 背景 |
| 未见物品 | 同类不同颜色/形状/材质的替换 | 未见物品 |
| 人为干扰 | 按官方 `human_1/4_note` 回放（移动/撤销/拿走） | 人为干扰 |
| 动作噪声 | 关节噪声、延迟、chunk 抖动 | 执行鲁棒性 |
| 过早释放 | 在放置前打开夹爪 | 接触/放置 |
| 碰撞 | 路径上加障碍/错误接近 | 恢复 |

**规模**：每任务每类 50-100 条，32 任务 × 5 轴 × 50 ≈ 8,000 条；与 33k 真实数据混合，合成占比 <25%。**外部数据默认 OFF**；CFE 只用官方数据 + 合成，不引入第三方数据。

### 5.3 人干扰剧本

官方 `info.json` 的 `generalization` 字段给出逐任务备注（第 7 轮已抓全 32 个；[S2]），例如：

- T27 StackBowls：human_1 把粉色碗向下移动；human_4 叠了第二个之后拿下第二个（先叠后撤）。
- T19 ZipUp：human_1 把包向左移动；human_4 拉上拉链之后拉开。
- T14 PourOutMedicine：human_1 拧开盖子之后拧动回来。
- T10 PlugCharger：human_4 将插头拔起。
- T24 ConveyorSorting：human_1/4 物品快到了然后放回传送带起点。

这些备注是**现成的干扰剧本**，可直接转成 CFE 场景；编号含义（轴/试次）未核实，但内容本身可用。

### 5.4 轴标签与平衡

- 官方评测每任务每轴 2 次；训练时按轴平衡采样，避免背景/位置轴主导。
- 轴标签来源：合成时已知；真实数据用 `info.json` 备注 + 视觉分类器弱标签。
- 轴不变键：物体相对位姿、EE 速度、光流、接触事件；避免全局外观键（背景轴会崩）。

## 7. 推理与部署

### 7.1 API wrapper

- 实现 `metadata`、`reset()`、`get_action(obs)`；`metadata` 声明 `control_space`、`obs_delta_indices`、`image_resize`、`action_chunk_size`。
- `reset()` 清 episode 内状态（step index、PWM hidden、时间预算）；CESM 的长期记忆是否清空由合规开关决定。
- 多端口：N 台机器人随机顺序，N 个连续端口从 8765；每个端口独立进程/状态，避免串扰。
- 健康检查/超时/重连；p99 延迟监控。

### 7.2 观测预处理

- 相机映射（见 §1.4）；`image_resize`：high 相机 224/256，wrist 256/320（腕部细节更重要）。
- `obs_delta_indices`：稀疏历史 `[-30, -15, 0]`（约 1s/0.5s/当前），用于进度/轴/undo 推断；不堆满所有帧，控制延迟。
- Proprio：双臂关节/EE、夹爪、lower_body；训练集多出的 `state_torso`/`state_d435` 在线上丢弃/重建。
- 语言：单字符串；训练时覆盖 5 复述 + 中文映射；推理时规范化。

### 7.3 延迟预算

- 目标：`get_action` p99 <100ms（单卡批量 N 端口）；chunk 16-32 步，控制频率 30-60Hz。
- PWM/heads 与 VLA 共享 backbone，额外开销 <10-20ms。
- 候选生成：N=4-8 在瓶颈步；普通步 N=1-2；批量生成，避免串行。
- 若 p99 超标：降 N、降分辨率、蒸馏 PWM、缓存检索；仍超标则关闭 CESM/降 MoE top-k。

### 7.4 时间预算管理器

- 180s 硬上限；每个任务预计 6-20s（官方演示中位 6-10s，长程 20-60s）。
- 预留最后 10-15s 给收尾/重试；瓶颈步优先；长程任务（T16/T17/T31）限 1-2 次重试。
- 超时前若未完成，执行安全停止/回退，避免撞机。

### 7.5 失败处理

- Undo 检测：PWM undo head + 视觉/本体事件；p(undo)>阈值 → 回退步骤。
- 重试：同候选扰动/换候选/regrasp；每次重试记录诊断标签。
- Abort：连续失败/时间不足 → 安全停止，保留步骤分（tiebreak 保险）。
- 记忆：成功段写入；失败段只写诊断，避免污染。

### 7.6 多机并发

- N 端口独立；每端口独立模型副本或共享 backbone + 请求队列；显存/延迟压测。
- 状态隔离：episode ID、step index、PWM hidden、时间预算按端口隔离。
- 日志：每步 obs/action/pwm/候选/选择/延迟；用于离线复盘。

## 8. 评测协议

### 8.1 离线

- 步骤级条件成功矩阵：每任务每步 p_{t,i}、置信区间；找瓶颈步。
- 轴敏感矩阵：每任务×轴的成功率/失败模式；找最弱轴。
- PWM 校准：ECE、Brier、候选排序准确率（top-1 是否选中最终成功候选）。
- 反事实回放：CFE 场景上的成功率/恢复率。
- 验收：瓶颈步定位稳定；PWM 排序 >60%；离线 SR +3pp 才进真机。

### 8.2 本地

- 回放/仿真混合：官方数据回放 + CFE 场景；不做模型选择的主依据。
- 配对 bootstrap：同任务/轴/种子；95% CI。
- 失败分类：抓取/放置/插入/闭合/undo/超时/碰撞；每类计数。

### 8.3 平台

- 不计分单任务调试通道（[S57]）：每大版本 1 次；优先 T27（StackBowls）、T10（PlugCharger）、T19（ZipUp）等瓶颈/恢复任务。
- 判定：瓶颈步 +10pp、整体 SR 不降、延迟达标；否则回退。
- 计分跑：W7 中期、W8 终期；若只能 1 次，留 W8。

### 8.4 统计决策

- 主要指标：总体 SR（32 任务宏平均）。
- 次要：每轴 SR、每任务 SR、步骤分（tiebreak）、延迟 p99、time-to-success、重试率、undo 恢复率。
- 检验：配对 bootstrap（10k 重采样）；SAVI 序贯检验（[S43]）；报告 95% CI。
- 决策规则：只有 95% CI 下界 >0 且点估计 ≥3pp 才上线；≥5pp 才作为主押注。

## 10. 创新点清单

> 状态：押注=本轮主线；保留=沿用；升级=旧点改造；降级=保留但非主回路；砍=不做。

### I1 成功率优先的测试时控制器（新增，押注）

- 动机：排名是 lexicographic，步骤分只破同分；现有 VLA 优化动作似然而非 episode success。
- 差异：把候选选择/重试/时间分配统一到“最大化整任务成功率”的 DP；不是 best-of-N 的简单堆叠。
- 可行性：控制器是确定性代码；PWM 是同 checkpoint head；API 支持 chunk/obs 裁剪。
- 资源：1-2 人周；无额外数据。
- 步骤：step graph → PWM → 候选打分 → DP → 调试槽。
- 风险：PWM 校准差 → 保守回退；延迟 → 降 N。

### I2 PWM 步级成功/撤销评论家（新增，押注）

- 动机：成功率是乘积；瓶颈步和 undo 是最大杠杆；现有模型没有显式预测。
- 差异：步级 + 整任务 + undo + axis 多 head；同一 checkpoint；反事实失败训练。
- 可行性：TLE 标签 + CFE 数据；head 参数量小。
- 资源：8×H100 4-6 天；CFE 8k 条。
- 步骤：TLE → CFE → 训练 → 校准 → 候选排序验证。
- 风险：OOD 过自信 → 温度/conformal/保守阈值。

### I3 轴感知上下文与 CESM（新增，押注/可选）

- 动机：5 轴×2 是评测结构；轴是最强的上下文变量；10 次运行有学习曲线。
- 差异：轴后验 + 轴不变键 + 同轴检索；不是全局外观检索。
- 可行性：官方备注/合成轴标签；记忆是数据；默认 OFF 合规。
- 资源：1-2 人周；缓存 <1GB。
- 步骤：轴 head → 记忆 schema → 检索 → flow 注入 → 合规开关。
- 风险：跨 episode 记忆合规 → 默认 OFF；轴变化快 → 同轴/轴不变键。

### I4 TC-MoE 单 checkpoint（新增，押注）

- 动机：DM0 specialist 62.0 vs generalist 37.3；UniBot 必须单模型全任务。
- 差异：按技能分组而非 per-task；router 条件化 task/step/axis；context dropout。
- 可行性：LoRA 专家 + 共享 backbone；4-8B 可控。
- 资源：2-3 周 LoRA；8×H100。
- 步骤：技能分组 → 专家训练 → router → 负载均衡 → OOD 验证。
- 风险：router 过拟合任务 ID → context dropout；专家塌缩 → load balance。

### I5 Soft chunk truncation + 时间预算（新增，工程）

- 动机：固定 chunk 与相位早停冲突；180s 硬上限。
- 差异：剩余 chunk 填 hold；按瓶颈步分配 N/重试。
- 可行性：纯控制代码。
- 风险：hold 动作可能被误判 → 安全回退。

### I6 CFE 反事实失败引擎（升级 ACP/GF）

- 动机：官方演示全成功；PWM 需要失败样本。
- 差异：5 轴 + 动作噪声 + 官方人干扰剧本；合成占比 <25%。
- 风险：合成-真实 gap → 调试槽真实失败补充。

### I7 Metric harness（新增，评测）

- 动机：320 episodes 高噪声；1-2pp 不可分辨。
- 差异：排名模拟 + 配对 bootstrap + SAVI + 功效分析。
- 风险：无；流程成本低。

### I8 底座 bake-off（新增，工程）

- 动机：底座选择影响延迟/许可/适配；方法层应解耦。
- 差异：同数据/同协议比较 WALL-OSS-0.5/UnifoLM-VLA-0/MolmoAct2/Spirit-v1.5。
- 风险：时间；1-2 周内完成。

### I9 Compliance compiler（新增，合规）

- 动机：单模型规则 + 外部数据/记忆开关。
- 差异：启动扫描 + 模型卡 + 审计报告。
- 风险：无；必须做。

### I10 保留/降级项

- 保留：TLE、检索式上下文、放置/恢复、统计评测。
- 降级：终局放置专项（并入瓶颈步）、TCLB（离线相对比较）、FLEET 检查单。
- 砍：步骤分优先、terminal-only、optimal stopping 保步骤分、14B WAM 主底座、外部数据主路径、全 32 任务高保真孪生、每任务 LoRA。

## 14. 开放问题

1. 外部数据/开源预训练权重是否允许？合成反事实数据是否算“外部数据”？
2. 跨 episode 记忆是否违反“10 次独立运行”？评测服务是否在任务/运行间重启？
3. N 台评测机器人的数量；端口并发/延迟上限。
4. 步骤分的精确聚合公式（每步部分分平均/最大/最终状态）；是否在超时后仍计步骤分。
5. 5 轴是否固定顺序/随机顺序；同一任务的 10 次是否在同一机器人/同一会话。
6. 官方指令是英文 5 复述之一、中文、还是未见复述？
7. 单模型定义边界：PWM/axis head/TC-MoE 是否都算同一模型；记忆/控制器是否需披露。
8. 不计分单任务调试通道的可用次数/成本/是否随机化泛化条件。
9. 真实榜单发布后，重跑“瓶颈步”假设；占位数据换成真实数据。
10. 是否需要提交模型卡/推理图/依赖清单；审计流程是什么。

## 15. 一句话押注

**把排行榜的 lexicographic 结构当第一性：成功率优先、步骤分只破同分；用同一 checkpoint 的“步级成功评论家（PWM）+ 轴感知上下文（axis posterior + CESM）+ 任务条件 MoE（TC-MoE）”做测试时推理控制，把算力集中在瓶颈步和可恢复失败上——这是本轮最值得押注的方向。**
