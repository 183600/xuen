# 第 4 轮（灵感循环第 4 轮；本轮灵感：「服务设计」×「状态隔离」）

> **基线**：第 3 轮 InstructGauge（IP-321–327；定义 432–447；引理 51–58；实验 E441–E456）。第 2 轮 ToolGauge、第 1 轮 LeanGauge / MODGAUGE 骨架继续继承不变。
> 本轮纪律：**增量升级 + 严格退化**。把「单租户顺序修复」升级为「多租户并发服务」，但服务化与隔离都是可选增强；任一组件不可用都必须能退回 InstructGauge 的单线程语义。

## 0. 直觉与动机

**灵感 1（服务设计 → 前店/后厂分道，而不是把所有逻辑塞进实时回路）**
直觉：服务设计的核心不是「客服态度」，而是**把可见的前台、不可见的后台、以及支撑流程用蓝图分开**，并规定它们在哪里交接、交接什么证据、失败时走哪条恢复路径。我们此前的系统其实已经有异步后台，但这些都是隐含约定：谁可以碰共享契约、证据在哪个时刻交接、后台重试会不会拖慢 50Hz 前台，都没有被显式建模。服务设计把这些隐含约定变成可审计的**服务蓝图**：前台 50Hz 只读快照、绝不阻塞；后台负责规划/校准/提交；审计作为独立的证据消费方。每一个 touchpoint 都是一次「证据交接」，有类型、有新鲜度要求、有失败语义。

**灵感 2（状态隔离 → 并发修复必须各有私域，但物理世界是共享的）**
直觉：多个盲区同时出现时，如果它们共享同一份可变状态（假设、块、局部校准），并发写会互相污染。快照隔离（规划读固定版本、提交用版本 CAS）能消除这种「混合契约」。但隔离有一个危险的副作用：它把「全局安全」偷换成「每个租户局部安全」的并集。热预算、执行器带宽、工作空间互斥、光学通道这些**物理资源**，以及共享计量契约的**一致性**，恰恰是隔离看不见的。因此隔离必须配一本共享账本：租约 + 全局不变量。没有这本账，隔离只是把冲突从显式变成隐式。

**灵感 3（两者耦合 → 服务化的隔离，必须有「跨租户组合安全」这一层）**
直觉：服务设计说「共享平台、多租户」；状态隔离说「各管各的状态」。两者结合最常见的系统性错误是**隔离-安全间隙**（isolation-safety gap）：每个 episode 的证书都正确，组合起来却违反全局约束——两个租户在各自快照里都是无碰撞的路径，合起来撞进同一条走廊；两个校准偏移各自在容差内，合起来互相矛盾。解法不是放弃隔离，而是三根新支柱：**可加资源核算的租约**（把全局约束写成每租户可分账的容量）、**快照隔离 + 静默点串行提交**（把共享契约的写变成全序事务）、**跨租户监控器**（对不可加/非单调约束做保守否决）。再叠加**幂等不可逆重试**与**舱壁**，防止服务化引入重试风暴与噪声邻居。

## 1. 研究问题（本轮要回答什么）

- **Q1（服务化的边界）**：哪些逻辑放前台、哪些放后台？能否证明前台时延不受后台负载（规划、重试、提交）影响，而不是靠"实测看起来没事"？
- **Q2（隔离的正确性）**：状态隔离在什么条件下能把「每租户局部安全」组合成「全局安全」？隔离-安全间隙 `Δ_iso` 何时非空、如何检测与封堵？
- **Q3（服务化引入的新故障）**：并发提交、重试、共享资源争用会不会制造级联失效与噪声邻居？幂等键、舱壁、SLO 错误预算各能压住哪一类？

## 2. 三条设计原则（雏形，正式化见产物区定义 448–463）

**P1 前台只读、后厂提交（Line-of-Visibility Separation）**
前台 50Hz 路径只读取不可变快照，绝不获取写锁、绝不等后台；后台通过版本 CAS 在静默点提交；审计只消费不可变证据总线。形式化方向：前台读路径与提交锁在内存模型上不相交（无锁读 + 原子发布），从而前台时延与后台负载解耦（引理 67）。

**P2 私有状态 + 版本化共享（Snapshot Isolation with Serializable Commit）**
每个修复 episode 是一个租户 `τ`，拥有私有状态 `S_τ`，无跨租户写别名；共享契约以单调版本 `v` 管理，规划/执行固定 `base` 快照，提交时 `CAS(base, Δ)`，失败则重基。形式化方向：隔离五公理 I1–I5（定义 451）+ 引理 59（无混合契约）。

**P3 共享资源先租后动 + 跨租户守卫（Lease-before-Effect + Global Invariant）**
任何对共享物理资源的作用必须持有未过期租约，且租约总和不超过容量；对可加/单调的全局不变量，租约本身即构成保守证明（引理 60）；对关系型/非可加不变量（空间互斥、共享偏移一致性），必须由跨租户监控器 `M_x` 保守否决（引理 61）。

## 3. 与基线的接口（如何退化）

- 单租户、无并发、`R_max=0` ⇒ 8C 闭环塌缩为 InstructGauge-7C（引理 66）；
- 快照/提交不可用 ⇒ 退化为 R3 的「静默点热替换 + 全局串行」；
- 租约不可用 ⇒ 强制单租户串行 + 全局不变量前置检查（退化为 ToolGauge 串行预算）；
- 跨租户监控不可用 ⇒ 拒绝一切非可加约束下的并发（宁降速不越界）；
- InstructGauge 失效 ⇒ ToolGauge ⇒ LeanGauge ⇒ MODGAUGE 原样。

## 4. 预期贡献

1. 一个显式的服务蓝图：前台实时、后台修复、审计证据三道分离，并给出前台时延与后台负载解耦的证明，而不是经验性 SLO；
2. 一组状态隔离公理与快照/提交协议，消除并发修复的混合契约，使「并发」不再是正确性的敌人；
3. 一个**局部安全 → 全局安全**的组合定理及其反例：可加约束下租约即充分，非可加约束必须跨租户监控——这把"隔离是否安全"从信仰变成可判定的结构性质；
4. 一套服务韧件（幂等不可逆、舱壁、SLO 错误预算、恢复自动机）阻止重试风暴与噪声邻居；
5. 一条完整可证伪路径：E457–E472 覆盖隔离泄漏、串行化、全局不变量、间隙搜索、租约、SLO、重试放大、幂等、重基、覆盖、分道、扩展、消融、对抗、崩溃恢复与 50Hz 保全。

## 5. 本轮最大风险

**一句话**：服务化 + 状态隔离会制造「每个租户都安全，所以系统安全」的错觉，而真正决定安全的是被隔离刻意隐藏的共享物理资源与共享契约一致性——若全局约束不可写成可加/单调的租约核算，`Δ_iso` 非空，局部证书的并发组合仍会越界，且这种越界在单租户测试里完全不可见。

## 2. 形式化定义（要点）

**定义 448（修复租户 τ 与私有状态 S_τ）** `τ = (k, s, ι, S_τ, base, L_τ, slo_τ)`，`S_τ = (H_τ, C_τ, cal_τ, ev_τ)` 分别为此租户的假设、块、局部校准与证据。令 `owner: Addr → TenantID ∪ {SHARED}`。**私有性**要求：任何写操作满足 `owner(addr) = k`；任何 `SHARED` 写只能经提交网关（IP-330）。租户关闭时 `S_τ` 整体回收，不留可被他人观察的可变残影。

**定义 449（服务蓝图 BP）** `BP = (F, B, A, TP, H, Ev)`：`F` 前台道（50Hz 读路径）、`B` 后台道（规划/校准/提交）、`A` 审计道（只读证据）。`TP` 为类型化交接点，`tp = (src_lane, dst_lane, payload_type, freshness F_tp)`；`H` 规定跨道只能经 `TP`；`Ev` 为不可变证据总线。**可见性线**：`F` 不得调用 `B` 的内部 API，只能读 `σ@v` 与 `tp`；从而前台无写锁、无后台等待（引理 67）。

**定义 450（版本化共享状态与快照）** `Σ_sh = (DPE, ledger, cal)` 带单调版本 `v`。`pin() → (v, σ@v)` 返回不可变视图；`CAS(v, Δ)` 仅当当前版本仍为 `v` 时原子地产生 `v+1`，否则返回 `Abort(v_cur)`。`rebase(Δ, v_cur)` 在新版本上重新校验 `φ_pre / ψ_post / 接地 / 租约`。快照一经发布不可变，写者以写时复制（COW）发布新版本。

**定义 451（隔离五公理 I1–I5）**
- **I1 私域无别名**：无跨租户可变状态别名；
- **I2 快照读一致**：一个规划—执行 epoch 内所有读来自同一 `σ@v`；
- **I3 串行化提交**：成功提交构成全序，原子应用且保持不变量，失败不改状态；
- **I4 租约纪律**：任何共享资源作用都持有有效租约，作用量不超过租约量；
- **I5 幂等不可逆**：不可逆动作携带幂等键，绝不重放；重试需全新独立回执。
五公理与 MODGAUGE 五不变式同构：前两条管「读到什么」，中间两条管「写到哪」，最后一条管「不能重来的东西」。

**定义 452（全局不变量 G_inv 与隔离-安全间隙 Δ_iso）**
`G_inv ⊆ Σ` 为系统级安全约束。`Δ_iso = { σ : (∀τ, σ_τ ⊨ Inv_τ) ∧ σ ⊭ G_inv }`。约定 `SvcGauge` 安全当且仅当 `Δ_iso ∩ Reachable = ∅`。当 `G_inv` 可租约表达时由引理 60 保证为空；否则须 `M_x` 守住。

**定义 453（租约资源治理 LSRG）** 资源集 `R`，容量 `C = (C_r)_{r∈R}`。租约 `ℓ = (τ, a, e, key)`，`a ∈ R_{\ge 0}^{|R|}`，`e` 到期时刻。**租约不变量**：`∀t, ∀r, Σ_{ℓ valid at t} a_{ℓ,r} ≤ C_r`。`acquire(τ, need)` 原子检查容量后签发；`release` 归还；过期由回收器清理。任何对资源 `r` 的作用 `u` 必须满足 `u_r ≤ a_{ℓ,r}`（先租后动）。

**定义 454（可加资源核算与租约可表达）** 对租户状态 `σ_τ` 定义资源占用 `f: Σ_τ → R_{\ge 0}^{|R|}`。若 `G_inv ≡ {σ : ∀r, Σ_τ f_r(σ_τ) ≤ C_r}` 且 `f_r` 单调，则称 `G_inv` **可租约表达**。此时若每租户 `f_r(σ_τ) ≤ a_{τ,r}` 且租约不变量成立，则全局成立——这把「隔离的组合安全」化为一次逐坐标求和。

**定义 455（SLO 与错误预算准入）** `slo_τ = (D_τ, F_τ, 1−β_τ, ε_τ)`：截止期、证据最大陈旧度、目标成功率、错误预算。准入采用 EDF 充分条件 `U = Σ_τ c_τ / D_τ ≤ 1 − η`，并检查提交率足以维持 `age ≤ F_τ`。不可行时按优先级降级（推迟到后台/搁置），绝不通过超发来"满足" SLO。

**定义 456（舱壁与断路器）** 舱壁为每类租户设并发上限 `b_c` 与队列上限 `q_c`；断路器状态 `{closed, open, half_open}`，连续失败达 `θ` 进入 `open`，冷却后半开试探。形式目标：任一租户的重试不得让其他租户的排队延迟超过 `q_c` 个服务时间（引理 63）。

**定义 457（幂等键与幂等应用）** `ik = H(k, ι, plan_hash, base)`。账本维护 `Applied` 集合。`idempotent_apply(op, ik)`：若 `ik ∈ Applied` 返回缓存结果（no-op）；否则在同一提交事务内应用并写入 `Applied`。不可逆动作必须带 `ik`；重试只能复用 `ik` 或凭全新独立回执重新规划，禁止盲目重放。

**定义 458（提交/重基协议 SIC）** 读写固定 `base`。在静默点 `t`：若 `v_cur = base` 则 `CAS`；否则 `rebase(Δ, v_cur)` 后重试，最多 `R_max` 次，指数退避加抖动；仍失败则中止并重新规划。每次提交生成版本号，供审计重放。

**定义 459（隔离感知修复证书 IACert）** `IACert(τ) = (RepairCert′(s), base, commit_v, {lease_ids}, G_inv witness, {ik}, slo_trace)`。它把 R3 的「指令→块→回执→主张」证据链，扩展为「租户→快照→租约→串行提交→主张」的服务级证据链；缺任一字段则降级为 `RepairCert′`。

**定义 460（服务恢复自动机 R_auto）** 对故障类 `{提交中止, 租约拒绝, SLO 违约, 上游过期, 监控否决}` 定义迁移；要求存在良基秩函数 `rank` 且总重试 `≤ B_retry`，杜绝 livelock 与无限重试。与 R3 的 `A_cond`（定义 443）共用良基性检查。

**定义 461（跨租户监控器 M_x）** 对非租约可表达约束，`M_x` 维护可达集保守过近似 `Over(σ)`，仅当 `Over(σ ⊕ Δ) ⊨ G_inv` 时放行提交。健全性要求过近似包含真实可达集（假阴性 = 0）；保守性只牺牲吞吐（假阳性）。对空间互斥用空间索引避免 `O(N²)`。

**定义 462（服务级效用）**
`U_svc = Σ_τ [ w_s·1{success} − w_D·(T_τ − D_τ)^+ − w_F·(age_τ − F_τ)^+ − w_a·aborts_τ ] − ∞·1{σ ⊭ G_inv}`。
最后一项把全局违约设为硬失败：任何吞吐/完成率收益都不能交换一次全局越界。

**定义 463（严格退化映射 Degrade）** 当 `|tenants| = 1 ∧ R = ∅ ∧ R_max = 0 ∧ base = v_cur` 时，`Degrade: SvcGauge → InstructGauge` 把 `S → I → H → C → E → T → V → U` 逐段映射到 R3 的 `I → H → C → E → C → V → U`：`S, T` 变为恒等/空提交，`TSI, LSRG, XTM` 变为直通。主循环逐指令等价，50Hz 路径不变。

```python
# IP-328 SVB：服务蓝图（前台只读 / 后台提交 / 审计消费）
class ServiceBlueprint:
    def __init__(self, front, back, audit):
        self.front, self.back, self.audit = front, back, audit
    def admit(self, tau):
        if not self.back.has_capacity(tau.cls):        # 舱壁
            return Defer("bulkhead_full")
        if tau.has_irreversible and not self.back.quiescent():
            return Defer("irreversible_requires_quiescence")
        return Admit(tau)

# IP-329 TSI：每个盲区一个隔离租户
class TenantStore:
    def open(self, s, iota, base, slo):
        tau = Tenant(s=s, iota=iota, priv=PrivateState(), base=base, slo=slo)
        self._by_id[tau.k] = tau
        return tau
    def write(self, tau, key, val):
        assert key.owner == tau.k                   # I1：无跨租户写别名
        tau.priv[key] = val
    def close(self, tau):
        tau.priv.wipe()                             # 私有状态整体回收
        self._by_id.pop(tau.k, None)

# IP-330 SIC：快照读 + 静默点 CAS 提交
class SnapshotStore:
    def pin(self):
        return self.version, immutable_view(self.state)   # 无锁读
    def commit(self, tau, delta, base):
        with self._lock:
            if self.version != base:
                return Abort(self.version)          # 交给 rebase
            if not self.invariants_hold(self.state, delta):
                return Reject("invariant")
            self.state = self.state.apply(delta)    # COW 发布
            self.version += 1
            return Commit(self.version)
    def revalidate(self, delta, v_cur):
        return (delta.pre_holds(self.view(v_cur))
                and delta.grounded(self.view(v_cur))
                and delta.leases_valid(v_cur))

# IP-331 LSRG：先租后动
class LeaseGovernor:
    def acquire(self, tau, need):
        with self._lock:
            if not all(self.used[r] + need[r] <= self.cap[r] for r in need):
                return None                         # 拒绝 => 排队/降级
            self.used += need
            lease = Lease(tau.k, need, expiry=now() + TTL,
                          key=hash((tau.k, need, self.epoch)))
            self.leases[lease.key] = lease
            return lease
    def release(self, lease):
        with self._lock:
            self.used -= lease.need
            self.leases.pop(lease.key, None)

# IP-332 XTM：非可加全局不变量（空间互斥示例）
def xtm_certify(mon, snapshot, delta):
    reach = mon.overapprox(snapshot, delta)         # 保守过近似
    if not spatial_mutex_holds(reach):              # 关系型约束
        return Veto("cross_tenant_collision")
    if not shared_offsets_consistent(reach):        # 非单调一致性
        return Veto("offset_inconsistency")
    return Certify(reach.witness)

# IP-333 幂等应用 + 服务恢复（有界重试）
def idempotent_apply(store, op, ik, tau):
    if ik in store.applied:
        return store.applied[ik]                    # 重放 => no-op
    res = op.apply()                                # 在提交事务内
    store.applied[ik] = res
    return res

def recover(M, tau, failure):
    plan = M.r_auto.transition(tau.state, failure)  # 良基 + 有界
    if plan.rank >= M.r_auto.max_rank or plan.retry > M.r_auto.budget:
        return Defer("recovery_budget")             # 不无限重试
    return plan

# IP-334 SvcGauge 8 段闭环：S→I→H→C→E→T→V→U
def svcgauge_8c(M, s, ell):
    # S：服务准入（SLO + 舱壁 + 不可逆静默检查）
    if not M.svb.admit(M.pending[s]):
        return Defer(s)
    # I：沿用 R3 接地；⊥ ⇒ 默认 ι
    out  = M.nlib.ground(ell, M.scene, M.ontology)
    iota = out[0] if out else M.default_iota
    # TSI + SIC：开租户并钉住快照
    base, snap = M.snap.pin()
    tau = M.tenants.open(s, iota, base, M.slo[s])
    # LSRG：先租后动；拿不到租约 => 降级而非硬闯
    lease = M.lease.acquire(tau, M.resource_need(iota))
    if lease is None:
        M.tenants.close(tau)
        return Defer(s)
    # H/C/E：沿用 R3，但只读 snap
    H = M.lbox.hypothesize(s, snap.R[s], iota)
    C = M.iac.plan_chunk(iota, H, M.tools, M.budget_left(s), M.drift_bound(s))
    cert = M.cvc.commit(C, snap.env, iota)
    delta = M.dpe_delta(cert, H)
    # T：提交前先过跨租户监控，再静默点 CAS
    if not M.xtm.certify(M.snap.state, delta):
        M.lease.release(lease); M.tenants.close(tau)
        return Defer(s)                             # 宁降速不越界
    res = M.snap.commit(tau, delta, base)
    if isinstance(res, Abort):
        if not M.snap.revalidate(delta, res.version):
            M.lease.release(lease); M.tenants.close(tau); return Defer(s)
        res = M.snap.commit(tau, delta, res.version)
        if isinstance(res, Abort):
            M.lease.release(lease); M.tenants.close(tau); return Defer(s)
    # V：校核 + 校准（沿用 R3）
    mu, Sig = M.apcal.calibrate(cert.receipts, H, s)
    M.apcal.update_contract(M.dpe, mu, Sig, s)
    # U：写审计 + 释放租约
    M.audit.write(IACert(tau, cert, base, res.version, lease, M.xtm.witness()))
    M.lease.release(lease)
    M.tenants.close(tau)
    return True

# IP-334 主闭环（50Hz 路径不变；前台只读快照）
def SvcGauge_round(M, obs, audio, tac, depth, det, ell=None):
    for s in M.dbox.detect_blind_spot():
        if s not in M.inflight and M.svb.admit_capacity(s):
            M.inflight.add(s)
            submit_async(svcgauge_8c, M, s, ell)    # 后台道并发
    return MODGAUGE_round(M, obs, audio, tac, depth, det)  # 前台道不变
```

## 4. 推导

**引理 59（快照隔离消除混合契约）** 在 I2 与 I3 下，任一租户的读集来自单一版本 `base`，提交要么原子地产生 `v+1`、要么不改状态；因此不存在读到"半应用"状态的执行，任意两个成功提交构成全序。混合契约事件概率为 0，且与线程交错无关。*证明*：`pin()` 返回不可变视图，`CAS` 在锁内比较版本并整体应用 `Δ`；读路径不持写锁，故读到的永远是某个完整版本。

**引理 60（可加约束下局部安全的组合性 / 租约定理）** 若 `G_inv ≡ ∧_r (Σ_τ f_r(σ_τ) ≤ C_r)`、`f_r` 单调、每租户受租约约束 `f_r(σ_τ) ≤ a_{τ,r}`，且租约不变量成立，则任意交错下 `Σ_τ f_r(σ_τ) ≤ Σ_τ a_{τ,r} ≤ C_r`，即 `σ ⊨ G_inv`。*证明*：逐坐标对单调函数求和，上界由租约与容量两级夹住；交错只改变求和顺序，不改变不等式。推论：对热预算、执行器带宽、总时长这类可加资源，隔离 + 租约即足以把局部安全组合成全局安全，无需全局锁。

**引理 61（非可加约束的隔离-安全间隙非空）** 若 `G_inv` 含不可写成单调逐租户求和的关系型约束（如空间互斥 `σ_τ ∩ σ_τ′ = ∅`，或共享偏移一致性要求 `o_τ = o_τ′`），则存在局部安全但全局违约的 `(σ_τ, σ_τ′)`，故 `Δ_iso ≠ ∅`。*反例*：两个租户各自在钉住的 `σ@v` 上规划出一条"当前无碰撞"的路径，二者都进入同一走廊的不同时刻却在中途相遇；单租户证书各自成立，合起来碰撞。另一反例：两租户各自把共享校准偏移调在 `+δ` 与 `−δ`（均在单租户容差内），组合后契约不一致。*结论*：非可加约束必须由 `M_x` 显式否决；`M_x` 的过近似若覆盖真实可达集则假阴性为 0，代价是假阳性带来的吞吐损失。

**引理 62（重基代价与新鲜度界）** 设并发提交到达率为 `λ_c`、单租户从钉快照到提交的时长为 `L`，则至少遇到一次冲突提交的概率 `p ≤ 1 − e^{−λ_c L}`，期望尝试次数 `≤ 1/(1−p)`；陈旧度 `age ≤ L + R_max·τ_backoff`。当 `p` 超过阈值 `p*` 时切换到单一提交通道，`age` 由排队界给出但安全不变。*证明*：冲突到达近似泊松，`1−e^{−λL}` 为标准冲突概率；重基次数受 `R_max` 限制，超过即中止重规划，故不会无界拉长陈旧度。

**引理 63（舱壁 + 幂等的重试稳定性）** 设每租户重试受令牌桶 `r_τ` 限制、全局服务率为 `μ`、基础负载 `λ`、利用率 `ρ = λ/μ < 1`。舱壁把在途并发限制为 `Σ_c b_c`，队列稳定；幂等键使重试在首次应用后成为 no-op，故有效负载放大因子为 `A = 1/(1−ρ)` 而非无界。噪声邻居给其他租户增加的排队延迟 `≤ q_c/μ`，被舱壁与队列上限双向夹住。*证明*：标准排队稳定性 + 幂等应用把重复请求折叠为恒等；令牌桶保证重试速率有界。

**引理 64（SLO 可调度与优雅降级）** 若 EDF 准入满足 `Σ_τ c_τ/D_τ ≤ 1−η`，且提交率 `≥ 1/F_τ`，则截止期与新鲜度均满足；若不可行，按 `U_svc` 优先级把低优先租户下放到后台或搁置。降级只降低完成率，不破坏 `G_inv` 与 `Inv_τ`。*证明*：EDF 充分条件；新鲜度约束等价于最大提交间隔，超过即拒绝新租户而非超发。

**引理 65（IACert 的可审计性与重放）** `IACert` 绑定 `base/commit_v`、租约集合、幂等键、`M_x` 见证与 SLO 轨迹；按版本序重放日志可重建提交状态，每条主张都能在对应快照内命中回执。删除隔离字段即退化为 R3 的 `RepairCert′`，且剥离仍是纯投影，不改变数值行为。*证明*：提交全序（引理 59）+ 幂等账本（定义 457）给出确定性重放；字段是证据的引用而非新计算。

**引理 66（严格退化到 InstructGauge）** 在 `|tenants|=1`、`R=∅`、`R_max=0`、`base=v_cur` 时，`S` 恒真、`T` 为空提交、`TSI/LSRG/XTM` 为直通，8C 闭环逐段等价于 R3 的 7C；再继承 R3 引理 57 → ToolGauge 引理 49 → R1 引理 44，主循环逐指令等价，50Hz 路径不变。新组件全部可选。*证明*：逐段替换为恒等映射，状态轨迹相同；退化映射 `Degrade`（定义 463）显式给出该对应。

**引理 67（前台时延与后台负载解耦）** 若前台只读不可变快照 `σ@v`、提交以 COW 发布新版本、读者不获取提交锁，则前台 p99 与后台提交/重试负载无关，只多一次指针读取与命令队列开销。*证明*：读路径无锁、无等待；写者原子发布后旧快照仍可读；不存在优先级反转，故后台再忙也不改变前台临界路径长度。这为「蓝图分道」给出结构性 SLO，而非经验值。

## 8. 本轮最大风险

**一句话**：`TSI` 的隔离与 `LSRG` 的租约只对**可加/单调**的全局约束构成完整证明；一旦真实系统里存在空间互斥、共享偏移一致性这类非可加约束，`Δ_iso` 非空，而 `M_x` 的保守过近似会把吞吐换成安全——最大的残余风险是我们**误把一条非可加约束当成可加约束**，于是每个租户的证书都正确、组合起来却越界，而且这种失效在单租户回归里完全不可见。
