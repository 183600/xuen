# 第 3 轮迭代（灵感循环：「任务规划」×「语义地图」）—— 从「逐步验证」到「计划—归因—修复」

> **直觉先行。** v2 把进度验证做成了“逐个计分步看有没有完成”。但真机上的失败很少是“某一步看不见”，而是**账本丢了**：物体被遮挡后忘了它还在不在、人手把已完成的状态退回去、机器人把“任务本身允许的回退”误当成干扰而反复重做。这一轮的两个词恰好是账本的两面——**语义地图**回答“现在世界是什么配置、谁动过它”，**任务规划**回答“按什么顺序推进、回退后修哪一段”。旗舰因此从 v2 的 RHPV-D 升级为 **SPARC（Semantic Plan-Attribution-Repair Controller，语义计划—归因—修复控制器）**：在语义地图上编译计分计划，用地图谓词做块边界巡检，用**反事实归因**区分“我失败”与“人撤回”，并只修复依赖闭包内的最小后缀。

**两条硬结论直接改变方案形态：**

1. **没有 depth/基座位姿/力 ⇒ 绝对公制 3D 地图与全局 SLAM 不可辨识。** 但计分谓词大多是**定性关系**（`on`/`in`/`stacked`/`inserted`/`closed`），它们只需要序与接触，不需要厘米级坐标。→ 建**定性语义图**，不建公制地图。
2. **`T_a` 是握手常量，动作块形状被硬校验。** v2 的 UIP-13 ACS“声明最大 k、运行期返回短块”不成立，必须退役；规划只能在**块边界**发生——这反而与“计划巡检”天然对齐。

### 0.1 可观测性审计（本轮方法论的核心）

| 想知道的量 | 接口内可辨识吗 | 可用代理 | 结论 |
|---|---|---|---|
| 绝对公制 3D / 全局位姿 | **不可**（无 depth、无基座位姿） | 单目深度头 + 手眼/EE 位姿提供**局部尺度**；跨遮挡会漂 | 不承诺公制；用定性关系 |
| 物体身份与持续存在 | 可（多视角跟踪 + re-ID） | 外观嵌入 + 空间近邻 + 手持状态 | 可做**物体永久性** |
| 相对关系（左/右/上/内/叠/插） | 较高 | 部件 mask + 投影 + 接触时的 EE 位姿 | 可做计分谓词 |
| 状态（开/合、拉链/未拉、到位/未到位） | 部分可 | 部件分割 + 时序差分 + 夹爪/EE | 可做，需拒识 |
| 变化是谁造成的（我/人） | 可（块边界） | **efference copy（我下发的动作）** + 时序对齐 + 反事实归因 | 可做，是本轮关键 |
| 步骤分是否“曾达成”还是“终局结算” | **未知** | 手册未公开 | 采用稳健策略，两种语义都不崩 |

> **命题（定性可辨识性，直觉版）**：若两个场景之间存在保序的空间变换（平移/旋转/缩放），且在四视图与 EE 位姿上产生相同的关系观测，则仅凭接口无法区分它们。因此系统应承诺**关系与状态**的可辨识性，而不是坐标的可辨识性；任何“无深度也能厘米级重建”的说法都应被视为不可检验的过度承诺。

## 1. 上轮清单诊断（v2 → v4 该升、该退、该改）

- **升级为旗舰**：UIP-01′（滚动验证）与 UIP-09′（撤回检测）合并升级为 **SPARC**。验证器从“视觉阈值分类器”换成“**语义地图谓词 + 反事实归因**”，重做从“当前子目标”换成“**最小依赖后缀**”。
- **退役**：UIP-13 ACS（自适应块长）。硬形状校验使其在接口层不成立；其“按阶段控反应性”的合理内核转移到 **UIP-19 VOI-MAP 的块内主动观测**与“离线按任务族选 `T_a`”。
- **职责升级**：UIP-11 GSO / UIP-12 DRF 从“计分神谕/造数据”升级为 **语义地图与谓词的标签工厂**——Gazebo 可直接给物体真值位姿、关系、接触与“谁动了它”，恰好补上公开数据没有关系标签的空白。
- **升级**：UIP-05（语言→可供性）→ **UIP-21 SGL′**，把语言绑定到地图节点/部件，而不是只做提示词；UIP-14（技能图）→ **UIP-22 TCM**，把“当前子目标 + 相关地图切片”作为策略条件，抑制长程漂移。
- **保留**：UIP-02′（计分步安全网，被 UIP-17 PTN 吸收）、UIP-08′（多端口延迟工程）、UIP-15 CSG（增加“重规划预算/归因置信门限”）。

## 2. 两个灵感词的解读（先直觉，再严谨定义）

### 2.1 语义地图：把“画面”改写成“关系账本”

**直觉**：人做家务并不在脑中维护一张厘米级点云；人维护的是“盖子已经拧开、碗叠好了两个、插头还差一点没到位、刚才那只手把锁拿走了”这样的**关系与状态账本**。它抗遮挡（杯子被手挡住也知道它还在），抗漂移（不需要绝对坐标），并且天然对接语言。

**严谨定义**：语义地图是带类型与属性的图 `M_t = (V_t, E_t, A_t)`：

- `V_t`：物体/部件节点。属性 `a_v = (类别, 颜色, 材质, 部件角色)`，状态 `σ_v ∈ {open/closed, zipped/unzipped, inserted/seated, stacked_on(·), held_by(·), visible/occluded/missing}`，位姿信念 `b_v = (μ_v, Σ_v)`（**桌面/base 局部系**，非世界系），以及 `holder ∈ {robot_L, robot_R, human, none}`。
- `E_t`：关系边，`left_of / right_of / front_of / behind / on / in / inside / stacked_on / aligned_with / part_of / held_by`。
- `A_t`：**归因层**，记录每个状态翻转的候选原因与证据（`self_skill`, `self_reverse_edge`, `external_agent`, `unknown`）。

**更新管线**：四视图检测+类无关分割 → 部件语言绑定 → 时序跟踪（ID 维持）→ 用单目深度/手眼尺度把 mask 投到 base 局部系 → 与上一帧做数据关联（匈牙利匹配 + 外观 re-ID）→ 更新图与不确定性。**遮挡不等于删除**：节点转为 `occluded`，保留最后位姿并膨胀协方差；只有当“最后一次可见 + 机器人未持有 + 多帧未重现”时才转 `missing`。

**为什么不做公制 SLAM**：见 §0.1 的定性可辨识性命题。公制坐标在无 depth、无基座位姿下会持续漂移，而计分谓词只吃关系，做公制是**用不可辨识的量去喂可辨识的判据**，只会放大方差。

### 2.2 任务规划：把“计分点”改写成“带权偏序计划”

**直觉**：计分点不是一张无序清单，而是一张**有先后、有权重、并且会被对手往回拨**的清单。好的执行不是“每步做完就打勾”，而是“按依赖推进、把脆弱的步安排在暴露窗口最小处、被拨回时只修受影响的那一段”。这就是规划，而不是反射。

**严谨定义**：设计分 DAG `G = (S, ≺, w)`：`S` 为计分步，`s ≺ s'` 表示顺序/依赖，`w_s` 为分值（Σ=100）。每个步 `s` 关联一个**地图谓词** `π_s(M) ∈ {true, false, unknown}`。进度势 `Φ(M) = Σ_s w_s · 1[π_s(M)=true]`。策略是信念上的映射 `π(a_{t:t+T_a} | b_t, G)`，目标是

```
max_π  E[ Φ(M_T) + λ·1[success] − μ·Var(latency) − ν·redo_cost ]
s.t.   action chunk shape = (T_a, …), single shared backbone
```

干扰被建模为**外生算子** `D`：在两个块之间把若干谓词从 `true` 拨回 `false`，或移动/移除节点。归因问题是：观察到的地图差分 `ΔM` 是否可由“我刚下发的动作块 `A`”解释？若不能，且翻转发生在块边界附近，则判为外部撤回。这给出本轮的旗舰定义：

> **SPARC = 在带权计分 DAG 上、以定性语义图为信念、以“地图谓词巡检 + 反事实归因 + 最小依赖后缀修复”为循环的执行控制器。**

### 2.3 两个词为什么必须合起来

- 只有任务规划、没有语义地图：计划是“盲计划”，不知道物体是否被移动/遮挡，谓词无从判断。
- 只有语义地图、没有任务规划：地图是“死账本”，不知道该复核哪一步、回退后修哪一段，容易在噪声里反复重做。
- 合起来：**地图是 belief，规划是 belief 上的 policy**；这正好把 v2 的“点验证”升级为“计划级闭环”。

## 3. 瓶颈假设（更新）

- **H1（最高杠杆）**：进度应定义为**地图谓词**而非像素分类；在无 depth/无力的接口上，地图差分 + 反事实归因是最可靠的 `regressed` 检测器。
- **H2**：计分 DAG 的顺序/权重结构应直接驱动执行与修复（偏序、保护性排序、残分打捞），而不只是事后核对。
- **H3**：无 depth/无基座位姿 ⇒ 公制重建不可辨识；**定性关系图**是更低方差、更贴合计分与语言的抽象。
- **H4**：不区分“自己合法回退”与“人撤回”的 `done→undone` 判据会大量假重做；归因是防止重做循环的关键。
- **H5**：计划级修复（只修依赖闭包）比逐步重试更能保住“已得分的前置步”，并显著降低动作浪费（见产物区 §9 合成实验）。

## 4. 候选与合并 → v4 清单

围绕两词发散 9 个草案，合并后得到 v4：旗舰 **UIP-18 SPARC**，两条基础腿 **UIP-16 SSM**（语义地图）与 **UIP-17 PTN**（计划编译），三个执行/优化机制 **UIP-19 VOI-MAP**、**UIP-20 SCORE-PO**、**UIP-21/22**（语言锚定与计划条件化）；UIP-11/12 职责升级为标签工厂。详见产物区。

## 5. 本轮最大风险

**一句话**：定性语义图的谓词在遮挡、堆叠与细接触下可能长期停在 `unknown`，而一旦把“未知”误当“未完成”去重做，或把“外部撤回”误判成“自己失败”，SPARC 就会退化成更昂贵的 v2 重做循环——因此必须把谓词输出限定为**带拒识的软证据**，并用“连续帧确认 + 归因一致 + 预算护栏”三重门控，且以真机小样本校准谓词阈值。

## 1. 旗舰深潜：UIP-18 · SPARC（Semantic Plan-Attribution-Repair Controller）

### 1.1 一句话与形式化

> SPARC 在带权计分 DAG `G=(S,≺,w)` 上执行；信念是定性语义图 `M_t`；每个计分步 `s` 有地图谓词 `π_s(M_t)∈{T,F,?}`；进度 `Φ(M)=Σ_s w_s·1[π_s(M)=T]`；块边界做三件事：**巡检**（谓词差分）、**归因**（我失败 / 我合法回退 / 人撤回）、**修复**（只重做依赖闭包内的最小后缀）。

目标（稳健版，不依赖未知的计分结算语义）：

```
max_π E[ Φ(M_T) + λ·1[success] − μ·Var(latency) − ν·#redo ]
s.t. 动作块形状 = (T_a,…)，推理期单骨干
```

### 1.2 运行循环（对齐固定 `T_a`）

```text
episode 开始:  M_0 ← SSM.build(首帧四视图, language);  plan ← PTN.compile(task.info)
每个 get_action(obs):
  1) M_t ← SSM.update(M_{t-1}, obs)                     # 跟踪/投影/数据关联
  2) 对当前计划窗口的每个 s: π_s ← Predicate(s, M_t)     # 带 unknown
  3) Δ = inspect(π, prev_π)                             # 哪些步翻转
  4) cause = Attribute(Δ, A_last, skill_graph, timing)  # 反事实归因
  5) if cause==external_regression: plan ← Repair(plan, s)   # 最小后缀
     elif cause==action_failure:   plan ← Retry(s)
     elif cause==intentional_undo: plan ← Advance()       # 任务允许的回退，不惩罚
  6) a_{t:t+T_a} ← Policy(obs, plan.current_subgoal, M_t.slice)   # UIP-22
  7) 可选：把块尾 1–2 步设计为 UIP-19 探针
  return action chunk
```

### 1.3 反事实归因（最关键的一步）

v2 的隐患是：很多任务本身就有合法回退（“开→合”“拧开→拧紧”“拉上→拉开”）。把所有 `done→undone` 都当外部撤回，会大量假重做。SPARC 把回退拆成三类：

```text
regressed(s) ⇔  π_s 由 T 变 F
             ∧ ( 翻转不能用“动作块 A 所属技能的合法反向边”解释 )
             ∧ ( 翻转在块边界附近，且地图差分与“外部移动/移除”一致 )
             ∧ 证据连续 k 帧一致（默认 k=2）

cause ∈ { self_skill_failure, self_reverse_edge, external_regression, unknown }
```

- `self_reverse_edge`：由技能图 `E-` 的合法反向边解释（例如“先打开再合上”中的合上）。
- `self_skill_failure`：我执行了该步但没做成（谓词一直 F，不是 T→F）。
- `external_regression`：原本 T，未被我触碰，突然 F 或节点被移动/移除。
- `unknown`：证据不足/分割拒识；**只前进，不重做**。

```python
def attribute(s, prev, cur, last_action, skill_graph, dt):
    if prev[s] is True and cur[s] is False:
        if skill_graph.explains_reverse(last_action.skill, s):
            return "self_reverse_edge"          # 任务允许，不惩罚
        if moved_by_external(prev, cur, last_action, dt) or object_missing(prev, cur):
            return "external_regression"
        if last_action.target == s:
            return "self_skill_failure"
        return "unknown"
    if prev[s] is False and cur[s] is False and last_action.target == s:
        return "self_skill_failure"
    return "none"
```

### 1.4 最小依赖后缀修复与残分打捞

```text
S_bad = {s : cause(s) == external_regression}
S_repair = dependency_closure(S_bad, G)          # 只含被回退步及其后继依赖
priority(s) = w_s · P(redo_success | M_t, c_t) / cost_time(s)
```

- **前置优先**：若被回退步是其他步的前置，立即修复，否则后续分也拿不到。
- **残分打捞**：若某回退不可恢复（例如人把关键物体拿走且找不到），把计划重排为“先完成**无依赖**的剩余步”，尽量把能拿的分拿到，再回头处理不可恢复步。
- **计分语义稳健性**：若不确定是“曾达成即入账”还是“终局结算”，对“是后续前置”的回退立即重做；对“无后继依赖”的回退，时间足够则重做，否则优先保后续步——两种语义下都不至于崩。

### 1.5 与 v2 的本质差异

| 维度 | v2 RHPV-D | v4 SPARC |
|---|---|---|
| 验证器 | 视觉/几何阈值 | 语义图谓词（关系+状态+归因） |
| 撤回判定 | `done→undone` 即 regressed | 归因后才 regressed，区分合法回退 |
| 重做范围 | 当前子目标 | 最小依赖后缀 + 残分打捞 |
| 规划 | 无显式计划 | 计分 DAG→HTN/BT，块边界巡检 |
| 反应性 | 想改 `k`（不成立） | 离线选 `T_a` + 块内探针（UIP-19） |
| 语义地图 | 无 | 持久物体/部件关系账本（UIP-16） |

## 2. 基础一：UIP-16 · SSM（Semantic Scene Memory）

### 2.1 图结构与状态

| 层 | 内容 | 例子 |
|---|---|---|
| 节点 `V` | 物体/部件实例 | `bowl#1`, `bowl#2`, `zipper_slider#1`, `rj45#1`, `port#1` |
| 节点属性 | 类别/颜色/材质/角色、状态、位姿信念、可见性、持有者 | `state=stacked_on(bowl#1)`, `holder=robot_L` |
| 边 `E` | 空间/功能关系 | `left_of`, `on`, `in`, `stacked_on`, `inserted`, `held_by`, `part_of` |
| 归因 `A` | 每次状态翻转的候选原因 + 证据 | `external_agent@{t}` |
| 不确定性 | 每节点/每谓词的置信度与 `unknown` | `π=?, conf=0.41` |

### 2.2 更新管线

```text
输入: 4×RGB, 双 EE 位姿(6+6), 关节(7+7), 夹爪(1+1), language
1. 检测/类无关分割 → 实例 mask + 部件 mask（共享骨干轻量头）
2. 语言锚定（UIP-21）→ 给部件打角色标签（拉链头/网口/碗沿/瓶盖…）
3. 跟踪 + 数据关联（匈牙利 + 外观 re-ID）→ 维持 ID
4. 投影：单目深度头 + 手眼尺度；接触时用 EE 位姿做尺度锚点
5. 关系判定：mask 重叠/包含/上下/接触时序 → π_s
6. 物体永久性：不可见 → occluded（不删除）；多帧未重现且非机器人持有 → missing
7. 输出 M_t（供巡检/规划/策略条件化）
```

### 2.3 尺度、坐标与可辨识性

- 坐标系：**base 局部系**（EE 位姿就是 base frame），不做世界系。
- 尺度：单目深度 + 手眼标定给局部尺度；**接触瞬间**用已知夹爪/物体几何校准，减少漂移。
- 只承诺**关系/状态**的可辨识性，不承诺公制坐标（见想法区 §0.1）。这使系统对相机标定误差、物体纹理变化更鲁棒。

### 2.4 数据关联与干扰后的恢复

- 人移动物体：节点位置先验突变 → 用“未被机器人持有 + 位置残差大 + 外观匹配”判为外部移动，保留 ID（尽量），必要时新增节点并合并。
- 人拿走物体：`missing` 节点保留最后位姿与外观；若之后重现则 re-ID 合并，避免“把它当成新物体”导致关系谓词错乱。

## 3. 基础二：UIP-17 · PTN（Plan-to-Network 编译器）

### 3.1 计分点 → HTN/BT

每个任务的 `scoring_points`（v2 表）编译为分层任务网络：

- **叶节点 = 计分步**，每个带 `{w_s, π_s(后置条件), skill_s, cost_s}`。
- **方法（method）= 任务分解**，例：`T27 StackBowls = [place(bowl1,center) → stack(bowl2,bowl1) → stack(bowl3,bowl2)]`，权重 `30/30/40`。
- **顺序来自计分点**；若任务允许多个物体互换顺序（如“把三样东西分别放进格子”），编译成**偏序**而非全序。

### 3.2 谓词库（示例）

```python
PREDICATES = {
  "T27": [("bowl1_at_center", 30), ("bowl2_on_bowl1", 30), ("bowl3_on_bowl2", 40)],
  "T19": [("bag_held_or_open", 50), ("zipper_closed", 50)],
  "T14": [("cap_unscrewed", 50), ("medicine_poured", 50)],
  "T26": [("rj45_grasped", 30), ("port_located", 30), ("rj45_inserted", 40)],
}
# 每个谓词实现为对 M_t 的确定性函数，返回 (bool, conf)
```

### 3.3 编译与执行

```python
def compile_task(info):
    steps = parse_scoring_points(info)          # 有序 + 权重
    preds = predicate_library[info.task_id]     # 语义图谓词
    dag = build_dag(steps, preds, partial=info.allows_parallel)
    return HTN(dag, skills=skill_graph)
```

执行时每个块边界只检查**当前计划窗口**（当前步 + 其后继），避免每帧全图重算。

## 4. 计分结构优化：UIP-20 · SCORE-PO

### 4.1 偏序与保护性排序

- 若计分允许，选择线性扩展 `ℓ` 使期望加权完成最大：
  `max_ℓ E[Σ_s w_s·1[π_s done by T]]`，约束 `≺`。
- **保护性排序直觉**：把“做完后容易被干扰拨回”的步尽量放在**暴露窗口小**的位置（靠近 episode 末、或紧接其依赖完成之后立即进入下一步），把“不可逆/稳定”的步前置。
- 这是一个**随机调度**问题：干扰按 hazard 率作用于已完成步，故顺序影响每一步的“存活概率”。

### 4.2 残分打捞

失败后不是“保前置、搏末步”这么粗，而是：
1. 先修**前置闭包**（不修则后续全丢）；
2. 再在剩余预算内，按 `w_s / cost_s` 贪心完成**无依赖**的剩余步；
3. 对已判 `missing` 的关键物体，若无法恢复则跳过其依赖子树，避免死循环。

## 5. 主动观测：UIP-19 · VOI-MAP

**直觉**：地图有时不确定（“插头到底进没进？”“碗到底叠稳没有？”）。与其猜，不如用**下一个动作换信息**。

**定义**：对不确定谓词 `π_s`，计算信息价值
`VOI(s) = E[ΔΦ | 观测 s] − cost(probe)`。
可执行的探针（受固定 `T_a` 限制，只能嵌在块内）：
- 块尾做一次“轻推-保持-回抽”或“小幅旋转-回位”，让接触/到位变成下一次观测可见的状态差；
- 把腕部相机移近目标（手臂小幅动作），提高部件分割置信度；
- 若探针无收益或风险高（可能弄倒已堆好的物体），不探，保持 `unknown` 并前进。

输出仍是**带拒识的软证据**：`unknown` 不触发重做。

## 6. 语言锚定与计划条件化：UIP-21 SGL′ / UIP-22 TCM

- **UIP-21 SGL′（升级 UIP-05）**：`observation.language` → 实体/部件/关系候选 → 与 SSM 节点做绑定（如 “红色杯子”“左边碗”“拉链头”）。对未见物体用**类无关分割 + 属性匹配 + 空间关系**，不依赖固定类别表。离线可用开放词汇模型打伪标签，**推理期只用共享骨干上的轻量头**。
- **UIP-22 TCM（升级 UIP-14）**：把“当前子目标 + 该子目标相关的地图切片（节点/关系/状态）”编码成条件 token 注入策略，抑制长程漂移；技能图仍是单骨干 + 参数高效技能头，满足单模型合规。

## 7. 标签工厂：UIP-11′ GSO / UIP-12′ DRF

- **UIP-11′ GSO（职责升级）**：Gazebo 不只给步骤分，还给**完美物体位姿、部件关系、接触事件、以及“是哪个 agent 改了什么”**。用它给 SSM 的谓词与归因打真值标签，离线训练/评测地图头。
- **UIP-12′ DRF（职责升级）**：按各任务 `human_*` 文本脚本化“反向撤回”（拧回、翻开、拉开、拿走、挪底座），生成 `(干扰前 → 撤回 → 恢复)` 轨迹，并同步记录地图差分与归因标签，专门训练 SPARC 的 `external_regression` 判别与修复。
- **边界**：仿真只做**结构/关系/顺序**的真值，不承诺像素级/接触力级保真；必须真机锚点校准（见 §10）。

## 8. 关键算法（合并伪代码）

```python
class SPARC:
    def __init__(self, policy, ssm, ptn, skill_graph, K=2,
                 conf_thr=0.6, max_redo=2, budget_ms=200):
        self.policy, self.ssm, self.ptn, self.sg = policy, ssm, ptn, skill_graph
        self.K, self.conf_thr, self.max_redo, self.budget = K, conf_thr, max_redo, budget_ms

    def reset(self):
        self.M = None; self.plan = None; self.redo = 0; self.t = 0

    def get_action(self, obs):
        self.M = self.ssm.update(self.M, obs) if self.M else self.ssm.build(obs)
        if self.plan is None:
            self.plan = self.ptn.compile(obs["observation.language"])
        prev = self.prev_pi
        cur = {s: self.ptn.eval(s, self.M) for s in self.plan.window}
        causes = {s: self.attribute(s, prev, cur, obs) for s in cur}
        for s, c in causes.items():
            if c == "external_regression" and self.redo < self.max_redo:
                self.plan = self.plan.repair(s)          # 最小依赖后缀
                self.redo += 1
            elif c == "self_skill_failure" and self.redo < self.max_redo:
                self.plan.retry(s); self.redo += 1
            elif c == "self_reverse_edge":
                self.plan.advance()                      # 合法回退，不惩罚
        self.prev_pi = cur
        a = self.policy.get_action(obs, self.plan.current, self.M.slice(self.plan.current))
        return a                                          # 形状 (T_a,…)

    def attribute(self, s, prev, cur, obs):
        if prev.get(s) is True and cur[s] is False:
            if self.sg.explains_reverse(obs, s):         return "self_reverse_edge"
            if self.ssm.external_move_evidence(s, self.M): return "external_regression"
            if self.plan.current == s:                   return "self_skill_failure"
        if prev.get(s) is False and cur[s] is False and self.plan.current == s:
            return "self_skill_failure"
        return "none"
```

> 注：`unknown`（置信度低于 `conf_thr`）在 `attribute` 中落到 `none`，即“不重做、继续收集证据”。

## 9. 玩具仿真结果（**合成，非真机**）

为了先验证“计划巡检 + 归因 + 最小修复”的决策逻辑，写了一个只依赖标准库的离散事件仿真 `exp/sparc_sim.py`（结果 `exp/sparc_results.json`）。它**不建模真实感知**，只对比四类控制器：

- `open_loop`：按序每步只尝试一次，不复查；
- `reactive1`：单帧谓词为假就重做；
- `reactive2`：连续 2 帧为假才重做（去抖）；
- `sparc`：持久信念 + 反事实归因 + 最小修复。

设定：技能单次成功率 `p=0.55`，干扰为每块以 hazard 把某个已完成步拨回，谓词有对称噪声。每场景 4000 episodes。指标中 `score/att` 是“每花一次动作拿到的分”，作为延迟/可信度成本的代理。

| 场景 | 控制器 | 步骤分 | 成功率 | 动作/局 | 浪费动作/局 | score/att |
|---|---|---:|---:|---:|---:|---:|
| 高干扰 30/30/40 | open_loop | 2.8 | 0.1% | 3.00 | 0.00 | 0.94 |
| | reactive1 | **91.4** | 77.3% | 20.48 | 8.49 | 4.46 |
| | reactive2 | 88.0 | 69.3% | 13.08 | 1.42 | 6.73 |
| | **sparc** | **88.5** | **70.1%** | 13.21 | **1.35** | 6.70 |
| 紧预算+高噪声 20×5 | open_loop | 29.3 | 0.9% | 5.00 | 0.00 | 5.85 |
| | reactive1 | 78.2 | 35.0% | 14.21 | 4.54 | 5.50 |
| | reactive2 | 81.4 | 42.5% | 11.33 | 1.59 | 7.19 |
| | **sparc** | **87.5** | **57.1%** | 11.96 | **1.39** | **7.32** |
| 高干扰（累计结算） | open_loop | 49.6 | 13.2% | 3.00 | 0.00 | 16.55 |
| | reactive1 | 100.0 | 100% | 20.48 | 8.49 | 4.88 |
| | reactive2 | 100.0 | 100% | 13.08 | 1.42 | 7.65 |
| | sparc | 100.0 | 100% | 13.21 | 1.35 | 7.57 |

**读法（诚实的结论）**：

1. **不复查的开环在干扰下崩塌**（2.8%–34% 分）：验证/巡检是必需的，与 v2 判断一致。
2. **无条件重做能拿到很高的分，但动作浪费是 SPARC 的数倍**（8–18 vs ~1.4 次/局）：在真实评测的延迟/可信度口径下，这是实打实的风险。
3. **SPARC 的优势主要在“每动作得分”和“紧预算+高噪声”下的绝对分/成功率**（87.5 vs 81.4/78.2，57.1% vs 42.5%/35.0%），而不是“无限时间下的最高分”。
4. **若是累计结算（达成即入账），干扰对分数影响变小**，此时归因的主要价值转为减少无谓重做与提高成功率；SPARC 与去抖相当，但更省预算。
5. **这是决策逻辑的玩具验证，不是机器人实验**；不构成对真机收益的承诺。

## 11. 合规与风险

- **单模型合规**：SSM/PTN/谓词/归因全部跑在**共享骨干上的轻量头 + 规则**；推理期绝不调用外部 VLM/开放词汇大模型。离线用 SAM2/GroundingDINO/Florence 打伪标签只算训练手段。
- **接口红线**：动作块必须严格 `(T_a, …)`、dtype `float32`、`meta.token` 每步携带；`obs_delta_indices`/`image_resize` 握手后不可改；只声明必要键以降低 JPEG 带宽/延迟。
- **地图风险**：遮挡/堆叠/细接触导致谓词长期 `unknown`；必须带拒识，`unknown` 不重做。
- **归因风险**：误判外部撤回会触发重做循环；用“连续 k 帧 + 合法反向边排除 + 预算上限”三重门控。
- **仿真过拟合**：GSO/DRF 只做结构/关系真值，不做像素/接触力真值；必须真机锚点校准。
- **计分语义未知**：手册未公开“曾达成 vs 终局结算”；采用 §1.4 的稳健策略，两种语义都不崩。
- **手册仍未取到**：5 轴中的“位置/干扰物/背景”与“评测轮次/时限/控制频率”仍待飞书手册公开后核实；本轮官网 HTTP 567，无法独立复取任务页。

**一句话**：定性语义图在遮挡、堆叠、细接触下若长期给不出可靠谓词，SPARC 的“归因—修复”就会建立在流沙上；错误归因会同时伤害成功率、步骤分与延迟可信度，因此必须把谓词与归因做成**带拒识的软证据**、用三重门控兜底，并以真机锚点校准阈值。

**→ 押注：UIP-16 SSM × UIP-17 PTN × UIP-18 SPARC 的“计划级巡检-归因-修复闭环”**——它把 v2 的点验证升级为对“世界配置 + 谁动过它”的显式建模，精确对准规则里白纸黑字的“反向撤回”干扰，同时用最小依赖修复压低动作浪费，完全落在选手 API 权限与离线算力之内。
