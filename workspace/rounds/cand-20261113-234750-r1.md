# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配交互消歧」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「双足机器人」×「状态机」）

> R69 把不确定性拆成 aleatoric / epistemic，并用「流匹配多模态策略 + 主动多模态交互」去消解后者。但它有一个从未被挑战的默认前提：**信息动作是廉价、可逆、随时可做的**；系统的动作空间不随「我现在站在哪里」而改变；「先看清再行动」几乎总是安全的。双足机器人同时推翻这三点。
>
> 双足行走的本质不是一条连续轨迹，而是一个 **hybrid automaton**：连续动力学在离散接触模式内流动，脚触地是带 guard 的跳变，跌倒是一个不可逆的坏模式。单脚支撑时，你不可能「停下来想清楚」——每多等一毫秒，捕获点就向支撑多边形外滑一点；而一次踏步既是动作，也是信息探针，还是不可轻易撤销的模式转移。**站立本身就是一个有时限的离散承诺。**
>
> 状态机正好补上另一块：模式、guard、invariant、transition、可达性与恢复。它把 R69 看不见的东西显式化——安全不是「动作幅度小一点」，而是「**永远存在至少一条通向安全模式的可控转移**」；不是「不确定就慢下来」，而是「**在截止时间前，选一个还能退回安全模式的承诺**」。
>
> 核心命题：**把 R69 嵌入一个混合模式机。连续层继续由流匹配策略在模式内生成多模态动作；离散层引入模式信念、guard、invariant、承诺截止时间与可行性核（viability kernel）；信息动作只有在其延迟能在截止时间前完成、且不耗尽逃生深度时才允许；否则必须立即做一个鲁棒承诺。** R69 成为「单模式、无截止时间、信息可逆、无模式混淆」的严格退化。命名 **STANCE-RAS**（State-machine Transition-Aware Non-deadlocking Commitment Envelope for Risk-Adaptive Systems）。
>
> 一句话定位：R68 问「我的测量还准吗」，R69 问「我该向谁求证、还能问什么」，R70 问「**我还来不来得及问，以及我这一步踏出去还有没有退路**」——在双足上，安全不是一个更小的数，而是一个尚未被关闭的离散模式。

## 0. 直觉与动机

**灵感 1（双足机器人 → 安全是离散生存问题，不是连续幅度问题）**
直觉：轮式底盘或固定基座机械臂可以「先停住再想」；双足不能。单脚支撑时，质心相对支撑点的运动由重力主导，捕获点（capture point）会持续外移；当它越出下一落脚可行域，摔倒就从一个概率事件变成一个几乎确定的动力学后果。更关键的是，**跌倒不是「更大的跟踪误差」，而是进入了一个不可逆的坏模式**：连续层的 λ 缩放、风险预算、保守控制器都救不回来，因为问题已经不在连续空间里了。双足还告诉我们：一个踏步同时是三件事——任务动作（前进）、信息探针（试探地面/摩擦）、模式承诺（把重心交给下一只脚）。因此 R69 的「先看/先问/先等」在双足上经常不是免费的观测，而是一次**用未来选择权换当前信息的交易**。

**灵感 2（状态机 → 把「承诺」显式化）**
直觉：状态机的真正价值不是「分支逻辑」，而是**把不可逆的离散承诺写成可验证的对象**：当前处于哪个模式、哪些 guard 允许离开、离开后进入哪个模式、该模式的不变式还能维持多久、是否存在回到恢复模式的路。行走就是一个典型的状态机：双支撑 → 左脚支撑 → 双支撑 → 右脚支撑 → ……；每一步都有 guard（落脚点可达、冲击速度有界、捕获点在可行域内）和 invariant（支撑多边形内、关节/力矩不越界）。安全需求也随之从「轨迹误差小」变成两个离散性质：**安全性 = 始终不进入无恢复边的坏模式；活性 = 始终至少存在一条通往恢复模式的可控转移**。这正是 Ramadge–Wonham 监督控制与 viability kernel 的语言。

**灵感 3（桥接 → R69 是「单模式、无截止时间、信息可逆」的退化情形）**
直觉：R69 的 VoI 公式默认信息动作不改变可行集，且可以无限等待。把它放进状态机后，信息增益必须乘上一个**截止时间门**：如果信息动作的端到端延迟大于「距离不变式失守还剩多少时间」，那么无论后验能降多少熵，它都不该被执行；更一般地，等待只会让可行性核单调收缩。于是得到一个反直觉但关键的结论：**在这里，「更保守」不等于「更安全」**。R69 的单调保守化（不确定 ↑ ⇒ 步长/动作幅度 ↓）可能因为错过必须迈步的时刻而**严格增大**跌倒概率。正确的决策对象不再是标量 λ，而是三元组 (λ, 当前模式, 承诺时刻)；可行 λ 的集合往往是一个区间，而不是一条「越小越安全」的半直线。

**灵感 4（不确定性再分层 → U_mode 与 U_model）**
直觉：R69 的 aleatoric / epistemic 都是**连续动作**层面的。双足引入两类新的、位置更高的不确定性：
- **U_mode（模式歧义）**：我现在到底是左脚着地还是打滑？是双支撑还是单支撑？接触模式是隐藏离散变量，必须由力/力矩、关节残差、IMU、足端运动学与视觉共同估计。模式错了，后续所有 guard 都在错误的世界上评估——这类错误不是「动作不确定」，而是「状态机状态不确定」。
- **U_model（模型不确定性）**：状态机本身是否还成立？换了负载、换了鞋底、地面从地毯变成冰面、guard 的感知模型漂移，都会让原来的可行性核与 guard 认证失效。R69 只需要担心策略密度；R70 还必须担心**离散安全模型本身是否过期**。
这两类不确定性不能塞进 R69 的 U_epi 里简单相加；它们需要独立的信念、独立的校准、独立的监控通道，以及「模型不可信时退回哪个更粗但更稳的模式」的策略。

**灵感 5（状态机是双刃剑 → 假安全证书比保守更危险）**
直觉：R69 的保守是「诚实的不知道」——不确定就慢下来，最坏是效率低。状态机却会给出一种更强的承诺：「这个 guard 已通过，这个模式已认证安全」。一旦状态机模型有偏、guard 被投毒、可行性核把「实际是死胡同」误判为「可恢复」，系统就会**带着一张看似完备的离散证书走进不可逆的坏模式**。更糟的是，离散证书会主动取消连续层的保守退路：既然「模式已认证」，就没有必要再慢下来了。因此 R70 必须同时交付：鲁棒 guard、模式信念校准、运行时模式混淆监控、恢复包络、机器哈希与离线重认证，以及「实时层零结构性改写」的红线。否则状态机不是安全层，而是一个更自信的谎话。

## 1. 形式化定义（增量：定义 310–326）

**定义 310（STANCE-RAS 总览）** STANCE-RAS = (HSM, MBE, VCG, CDS, HFP, V2I, MSC, MCR, REE, RAS-WM‡)。五条不变式：
(i) **实时流零学习写操作**（继承 R69 定义 293-i）；
(ii) **无未认证承诺**：任何模式转移 e 必须属于鲁棒安全转移集 A_safe，且转移后逃生深度 d ≥ d_min；
(iii) **截止时间诚实**：信息动作只有在其延迟满足 ℓ(g)+ε_r < τ_q(x)、且执行后可行性核仍非空时才可执行；禁止「等到不变式快失守才反应」的被动等待；
(iv) **模型认证**：HSM 的结构、guard、reset、可行性核与恢复包络全部版本化，证书带 machine_hash；实时层不得结构性改写状态机；
(v) **严格包含**：在 |Q|=1、τ=∞、𝒜_act=∅、无模式混淆的退化机上，STANCE 与 FLUID-RAS 逐指令一致。

**定义 311（混合模式机 HSM）** H = (Q, E, X, U, {f_q}, {Inv_q}, {G_e}, {R_e}, {D_q})。Q 为有限接触模式集，默认 Q = {DS, LS, RS, FL, REC}（双支撑 / 左单支撑 / 右单支撑 / 飞行 / 恢复）；X 为连续状态（质心、质心速度、关节角与角速度、接触力、CoP 等）；U 为连续控制。模式 q 内 ẋ = f_q(x,u)，u ∈ U_safe。Inv_q = {x : m_q(x) ≥ 0}，其中 m_q 为安全裕度（CoP/CoM 在支撑多边形内、捕获点落在下一落脚可行域、关节/力矩/速度不越界）。e=(q,q') ∈ E，guard G_e ⊆ X×U 必须带鲁棒裕度 δ_g 成立，reset R_e : X→X 描述冲击/换脚。D_q(x) 为模式最大允许驻留时间。模式序列 σ=(q_0,e_1,q_1,…,e_m,q_m) 合法，当且仅当所有 invariant、guard 与 deadline 同时满足。

**定义 312（模式信念 MBE）** 令 b_t ∈ Δ(Q) 为离散模式后验。混合观测器更新：
b_{t+1}(q') ∝ Σ_q b_t(q) · T(q'|q,u_t) · L(y_{t+1}|q',x_{t+1})，
其中 T 为模式转移先验，L 由足端力/力矩、关节力矩残差、IMU、足端运动学与视觉接触证据构成。模式熵 H_b = −Σ_q b_t(q) log b_t(q)；ε-支持 Q_ε(b) = {q : b_t(q) ≥ ε} ∪ {argmax_q b_t(q)}；模式混淆风险 κ_t = 1 − b_t(q̂_t)。模态校准要求 ECE_mode ≤ τ_ece，否则模式级决策退化为「对 ε-支持取最坏情况」。注意：U_mode 不是 aleatoric 噪声；它有时可以被一次探针步降低，但探针步本身是一次模式转移。

**定义 313（可行性核与逃生深度）** 设 R ⊆ Q 为预先认证的恢复模式集。逃生深度 d_q(x) 递归定义：
- 若 q ∈ R 且 m_q(x) ≥ 0，则 d_q(x) = 0；
- 否则 d_q(x) = 1 + max_{e=(q,q')∈E, ∃u 使 G_e(x,u) 成立且 R_e(x) ∈ V_{q'}} d_{q'}(R_e(x))；
- 若无可用转移或落在不变式外，则 d_q(x) = −∞。
可行性核 V_q = {x ∈ Inv_q : d_q(x) ≥ 0}。d≥1 表示「还有至少一条安全出路」；d=0 表示已在恢复集；d=−∞ 表示死端。工程上以网格/神经网络证书离线计算保守近似，在线只做查表。

**定义 314（承诺截止时间与时延可行性）** 对模式 q 与状态 x，定义
τ_q(x) = inf{t ≥ 0 : 在最佳可行性保持流下 x(t) ∉ Inv_q}，
即距离不变式失守的保守时间。信息动作 g 的端到端延迟为 ℓ(g)，反应裕度 ε_r，决策时间 τ_dec。截止时间松弛
s_q(x,g) = τ_q(x) − ℓ(g) − ε_r − τ_dec。
g 可行（admissible）当且仅当 s_q(x,g) > 0，且执行后状态仍在 V_q 内并保持 d ≥ d_min。承诺集 C_q = {x : 不存在可行的信息动作 g}。在 C_q 中，系统必须立即承诺，而不是继续观测。这是「停下来想清楚」在双足上的正式死亡。

**定义 315（混合流策略 HFP）** 在 R69 的连续流匹配之外增加一个离散模式头 p_φ(σ|z_t,b_t)，并为每个模式序列条件化一个速度场 v_θ(x_s,s|z_t,σ,b_t)。训练目标
L_HFP = E‖v_θ(x_s,s|z_t,σ,b_t) − (x_1 − x_0)‖² − λ_ce log p_φ(σ_obs|z_t,b_t)，
其中 x_1 为模式内的连续动作块，模式切换处施加 reset R_e。采样时从 p_φ 抽取 K 条混合计划，再在每条计划内用 1–2 步 rectified flow 生成连续控制，解码为 (a, g, σ)。任何计划在执行前必须先过 VCG 的模式序列认证。

**定义 316（信息动作的二分：被动观测与主动探针）** 把 R69 的 g 拆成两类：
- **被动观测** g^pass = (g_gaze, g_ask)：不改变接触模式，延迟 ℓ_pass，近似可逆；
- **主动探针** g^act = (g_probe, g_step)：本身是一次模式转移 e_probe（例如试探步、重心转移、轻触支撑），延迟 ℓ_act，**消耗逃生预算且不可撤销**。
故 𝒜_info = 𝒜_pass ⊔ 𝒜_act。主动探针必须同时通过信息可行性（定义 314）与安全转移认证（定义 318）；它不能只是「多看一眼」，而是「用一步去换信息」。

**定义 317（可行性门控 VoI，V-VoI）** 对信息动作 g，定义
V-VoI(g) = D_q(x,g) · [H(b_t) − E_{y∼p(·|g,o)}H(b_{t+ℓ}|y)] − c_pass(g) − c_irrev(g) − c_risk(g)，
其中 D_q(x,g)=1 当且仅当 g 满足截止时间与逃生深度约束，否则为 0；c_irrev 对主动探针计入逃生预算消耗与不可逆风险。选择
g* = argmax_g V-VoI(g)，要求 V-VoI(g*) > 0 且 g* 通过安全认证；否则不交互，转入定义 318 的立即承诺。软版本可把 D 替换为 D_soft = σ((τ_q − ℓ(g))/τ_0)，但硬门在安全认证中不可省。

**定义 318（鲁棒安全转移集与模式监督器 MSC）** 对当前模式 q、状态 x、模式信念 b，定义
A_safe(q,x,b) = { e=(q,q') : ∀q̃ ∈ Q_ε(b), G_e(x,u) 以裕度 ≥ δ_g 成立，R_e(x) ∈ V_{q̃}，d_{q̃}(R_e(x)) ≥ d_min，且若 e 兼作信息动作则 s_q(x,g_e) > 0 }。
模式监督器选择
e* = argmax_{e∈A_safe} [V_task(e) + γ·V_escape(e) − R(e) − c(e)]，
同分时选鲁棒裕度更大者。若 A_safe = ∅，不得选择任何未认证转移，只能进入 REE 恢复。A_safe 是离散层的「安全盾」：学习策略只能在其内部排序，不能改写其边界。

**定义 319（两级风险与保守性的非单调）** 连续层在模式 q 内沿用 R69 的 λ 缩放；离散层使用承诺三元组 (q,e,b) 与可行性三元组 (d,s,margin)。认证时域
k = min(k_R69, k_V, k_D)，
其中 k_V 来自可行性核的保持时域，k_D 来自截止时间。定义模式风险
R_mode = P(b_t ∉ 安全支持) + P(guard false-safe)。
关键：令 Λ_safe(x) 为「既能在截止时间前完成必要承诺、又不违反不确定性与动力学约束」的 λ 区间。R69 的单调保守化倾向于把 λ 推向区间下端；当 λ < λ_min(τ) 时，系统会因过度保守而错过必须迈步的时刻。故不确定 ↑ ⇒ 只收紧 在混合系统中不成立；正确对象是 (λ, 模式, 承诺时刻) 的联合可行域。

**定义 320（模式混淆运行时监控 MCR）** 监控残差向量至少包含：
(i) invariant 裕度残差（预测 CoM/CoP 与实际）；
(ii) guard innovation（预测触地时刻/位置/冲击速度与实际）；
(iii) 驻留时间偏离（dwell-time anomaly）；
(iv) 跨通道模式分歧（F/T、关节残差、IMU、足端运动学、视觉）。
定义 Λ_t 为归一化残差最大值。若 Λ_t > τ_conf 或 ECE_mode > τ_ece，立即冻结模式转移决策、扩张 ε-支持、缩短认证时域、提高连续层保守度，并只允许进入预先认证的恢复/鲁棒模式。MCR 是 R69 的 FMA/CIA 在离散层的第二意见：连续层测「行为自洽」，离散层测「模式自洽」。

**定义 321（恢复包络与逃生预算 REE）** R ⊆ Q 为预先认证的恢复模式集，π_rec 为恢复策略；每个恢复模式带恢复时间 t_rec(q,x)、成功概率 p_rec 与损害上界 ε_rec。逃生预算 ρ(x) = d_q(x)（或深度/时间/能量的加权账本）。硬规则：ρ ≥ ρ_min 恒成立；ρ < ρ_min 时禁止主动探针与高风险转移；ρ = 0 时执行恢复。REE 是 λ_floor 的离散对应物：不是「概率在变小」，而是「还剩几条命」。

**定义 322（机器认证边界与版本化 guard）** 认证状态机 H_cert 固定 (Q,E,Inv,G,R) 的结构与 guard 参数集 Θ_G 的认证包络；实时层不得结构性修改。machine_hash h_H = Hash(Q,E,Inv,G,R,Θ_G,VCG_version,REE_version)。任何负载、足端、地面类别、控制器或感知模型的改变都触发离线重认证；在重认证完成前，J_STANCE 无效。若观测到的 guard 分布越出认证包络，MCR 将其视为模型漂移而非普通噪声。

**定义 323（混合威胁模型 ℰ_STANCE）** ℰ_STANCE = ℰ_FLUID × ℰ_mode × ℰ_machine：
- ℰ_mode：接触欺骗（软地毯、冰面、湿滑）、打滑、触地延迟、足端遮挡；
- ℰ_machine：guard 投毒（感知把不安全落脚点报成安全）、状态机陈旧（负载/硬件变化）、可行性核投毒（地图声称有恢复路但实际被堵）、延迟攻击（把信息动作拖过截止时间）；
- ℰ_social：在交互/提问期间推搡、触碰或诱导系统进入单支撑。
每一类扰动必须映射到至少一个监控通道与一个已认证恢复动作，不能只靠「模型应该没错」。

**定义 324（证书 J_STANCE）** J_STANCE = (J_FLUID, mode_ece, H_b_p95, viability_margin_min, escape_depth_min, deadline_slack_min, guard_innovation_p95, recovery_time_max, machine_hash, stance_ver)。Valid ⇔
Valid(J_FLUID) ∧ mode_ece ≤ τ_ece ∧ viability_margin_min ≥ 0 ∧ escape_depth_min ≥ d_min ∧ deadline_slack_min > 0 ∧ 所有已执行转移 ∈ A_safe ∧ machine_hash 与认证版本一致 ∧ REE 非空。

**定义 325（双速率执行契约）** 三个硬实时层：
- **1 kHz 快速安全盾**：解析 guard + 可行性查表 + 恢复动作，P99 < 0.25 ms；
- **200 Hz 模式监督器**：A_safe、V-VoI、承诺选择，P99 < 0.9 ms；
- **50–100 Hz 混合流规划器**：K 条混合计划生成，P99 < 3.5 ms。
证书与审计异步。若规划器超时，快速安全盾保持上一个已认证的安全承诺或直接进入 REE；**超时本身被视为一次模式混淆事件**，而不是普通计算延迟。

**定义 326（条件化 resolution bonus）** R69 的 resolution bonus 在 R70 中必须带四个条件才生效：
(a) 信息动作在 τ_q 前完成；(b) ECE_mode 在界内；(c) 消解后 d ≥ d_min；(d) 无 MCR 告警。
四者同时满足时，连续层才可只按 U_ale 设定 λ；否则按 U_ale + 未消解 U_epi 处理，并保持模式级鲁棒承诺。R69 的 bonus 从「自动获得」变成「必须同时买到时间、模式和退路」。

```python
        return False, -1

            for q2 in grid.enabled(x, q, b)]

    return d >= D_MIN, d

# IP-267 CDS：承诺截止时间与信息动作可行性

# IP-268/269 HFP + V2I：模式条件流采样 + 可行性门控 VoI
def plan_and_gate(policy, b, x, budget):

    plans = policy.sample_hybrid(x, b, K=adaptive_K(b))
    best = None
    for g in info_candidates(plans, Qeps):
        if not budget.allow(g):
            continue
        if deadline_slack(x, q_hat, g, VCG) <= 0:     # 来不及问
            continue
        if not preserves_depth(g, x, b, VCG):         # 问完没退路
            continue
        score = info_gain(b, g) - cost(g) - irrev_cost(g) - risk(g)
        if score > 0 and (best is None or score > best.score):
            best = (g, score)
    if best is not None:
        return ("INFO", best[0], plans)
    return ("COMMIT", supervisor_choose(plans, b, x), plans)

# IP-270 MSC：对模式信念的 ε-支持取最坏情况的鲁棒安全转移
def supervisor_choose(plans, b, x):
    cand = []
    for e in transitions(x, q_hat):
        if all(guard_ok(e, x, q2, DELTA_G) and
               reset_in_kernel(e, x, q2) and
               depth_after(e, x, q2) >= D_MIN
               for q2 in support(b, EPS_MODE)):
            cand.append((e, value(e, plans) - risk(e) + GAMMA * escape_value(e)))
    if not cand:
        return ("RECOVER", recovery_policy(x))        # 无死锁兜底
    return max(cand, key=lambda z: z[1])[0]

# IP-275 STANCE 主闭环
```

## 3. 推导

**引理 19（截止时间对 VoI 的截断）** 设模式 q 在 x 处的时间-承诺为 τ_q(x)，信息动作 g 的端到端延迟为 ℓ(g)，反应裕度为 ε_r。若 ℓ(g)+ε_r ≥ τ_q(x)，则对任意后验更新，等待 g 的期望风险不低于立即承诺，且 V-VoI(g) = 0。一般地，有效信息增益 ≤ 1[τ_q(x) > ℓ(g)+ε_r] · [H(b_t) − E H(b_{t+ℓ}|y)]；而等待期间可行性核单调收缩：V_q(x(t)) ⊆ V_q(x(0))。系：**R69 的 VoI 是 τ=∞ 的退化情形**；在双足上，「再等一帧」不是零成本，等待的价值随时间被双重折扣——信息可能来不及，退路同时在变少。

**引理 20（无死锁承诺的归纳安全性）** 若每次承诺的转移 e 满足：对所有 q̃ ∈ Q_ε(b)，R_e(x) ∈ V_{q̃} 且 d_{q̃}(R_e(x)) ≥ d_min，guard 鲁棒裕度 ≥ δ_g，则沿任意执行，逃生深度至多每次承诺减少 1，最多 d_min 次承诺内可达恢复集 R；期间不会进入死端。证明：对承诺次数归纳。初始 d ≥ d_min；每次进入 V_{q'} 且 d 至少为 d_min，递归定义给出下一步仍有安全转移；恢复集内 d=0 且 invariant 保持。系：**安全性可以写成一个离散的「剩余承诺次数」不变量**，而不是一个需要实时重新估计的连续概率。

**引理 21（模式辨识与可行性的时间权衡）** 设相邻接触模式在观测分布上的 Chernoff 信息为 D，则用 T 时间观测后模式错误概率 ≤ exp(−T·D)。但同一 T 消耗可行性时间，使可用承诺时间从 τ_q 降为 τ_q − T。故总风险上界近似为
R(T) ≲ exp(−T·D) + P_fall(τ_q − T)，
对 T 求导得最优停留时间 T*；当 τ_q − T ≤ ℓ(g)+ε_r 时 T* = 0。系：**「多看一眼」的价值随剩余时间指数衰减**；在单脚支撑末期，最优策略往往不是看，而是迈。这也解释了为什么 R69 的「先消歧再行动」不能直接搬到双足。

**引理 22（主动探针的逃生预算守恒）** 任何 g^act 都对应一次模式转移 e_probe，因此至少消耗 1 单位逃生深度：ρ_after ≤ ρ_before − 1（最好情况）。若 ρ_before = ρ_min，则任何主动探针都不可采纳，只能被动观测或立即承诺。系：**信息不是免费的**；在双足上，「踩一脚试试」与「走一步」在资源账本上是同一类动作，不能把它当作 R69 那种廉价 g。

**定理 18（STANCE 严格包含 R69）** 在 |Q|=1、τ=∞、𝒜_act=∅、信息可逆、ECE_mode→0 的退化机上，A_safe 退化为全部动作，V-VoI 退化为 R69 的 VoI，STANCE 与 FLUID-RAS 逐指令一致；R68 再作为 R69 的「永不交互」边界。反之，存在双足状态使 R69 的「等待消歧」必然错过承诺截止时间而跌倒，STANCE 通过截止时间门选择立即承诺而避免。因此包含是严格的：安全侧不弱于 R69，且在有时限的混合系统中严格更强。

**定理 19（混合安全证书）** 在 A99–A103 下（可行性核保守、guard 经认证、模式信念校准、MCR 阈值有效、恢复包络非空），STANCE 在任意执行中以概率 ≥ 1 − δ_total 不执行未认证转移，其中 δ_total = δ_machine + δ_belief + δ_guard + δ_monitor；若 A_safe = ∅ 则进入 REE，损害 ≤ ε_rec；连续层在模式内仍保持 R69 的 λ_floor 安全界。证明：离散层由引理 20 的归纳不变量给出；连续层由 R69 定理 16–17 给出；二者的耦合只在已认证转移处发生，故风险可加。

**定理 20（保守性的非单调——对 R69 的正面反驳）** 存在混合系统状态 x、模式 q 与不确定性 U，使得 R69 的单调保守化（U ↑ ⇒ 步长/动作幅度 ↓）严格增大跌倒概率：双足在单脚支撑末期必须迈出至少 l_min 的一步，才能把捕获点拉回下一支撑域；保守化把步长压到 l_min 以下，反而使捕获点越界。更一般地，STANCE 的可行 λ 集是区间 Λ_safe(x) = [λ_min(τ), λ_max(U)]；当区间为空时，唯一正确的动作是切换到恢复模式，而不是继续降低 λ。故「不确定 → 只收紧」在混合系统中不成立；正确的偏序是 (λ, 模式, 承诺时刻) 的三元组偏序。系：**状态机的加入不是给 R69 再加一层刹车，而是给它换一套「什么时候必须踩油门」的规则**。

## 6. 本轮最大风险

**一句话**：STANCE 把安全从「连续地慢下来」变成「离散地进入一个已被认证的模式」；**状态机、guard 与可行性核只是模型，一旦它们有偏、陈旧或被投毒，系统会带着一张看似完备的证书走进死胡同——离散的假安全比连续的保守更致命，因为前者会主动取消后者本来提供的退路。**

**次级风险与缓解**：
1. **模式混淆**（接触误判 → 错 guard）→ MBE 多通道 + MCR + ECE_mode 门控；模式不可信时只做最坏情况承诺；
2. **可行性核过保守**（频繁恢复、任务能力下降）→ 离线保守核 + 在线 margin 调参 + E314 的 Pareto 分析；
3. **主动探针耗尽逃生预算** → 引理 22；ρ < ρ_min 禁止主动探针，只用被动观测或立即承诺；
4. **截止时间估计偏差** → 保守 τ 估计 + 双速率安全盾 + 超时即恢复；
5. **状态机陈旧/载荷变化** → machine_hash + 离线重认证 + 实时层零结构性改写；
6. **guard 投毒/假安全证书** → ℰ_STANCE 对抗训练 + MCR + E306/E307；证书只能证明「在认证模型内安全」，不能证明「模型正确」，故必须同时审计模型版本。

## 2. 形式化定义（要点版）

**定义 310（总览与五不变式）** STANCE-RAS = (HSM, MBE, VCG, CDS, HFP, V2I, MSC, MCR, REE, RAS-WM‡)；零学习写操作继承；无未认证承诺（e∈A_safe 且 d≥d_min）；截止时间诚实；模型认证与 machine_hash；退化机上严格包含 R69。

**定义 311（HSM）** 模式 q 内 ẋ=f_q(x,u)，u∈U_safe；Inv_q={x:m_q(x)≥0}；转移 e=(q,q') 带 guard G_e 与 reset R_e；D_q 为最大驻留；模式序列 σ 必须同时满足 invariant/guard/deadline。

**定义 312（MBE）** `b_{t+1}(q') ∝ Σ_q b_t(q)T(q'|q,u)L(y|q',x)`；输出 `H_b`、`Q_ε(b)`、`κ_t=1−b(q̂)`；ECE_mode 越界则对 ε-支持取最坏情况。U_mode 是可被探针步降低、但要消耗模式资源的离散 epistemic 不确定性。

**定义 313（可行性核与逃生深度）** `R` 为恢复模式集；`d_q(x)=0` 若 q∈R；否则 `d_q(x)=1+max_e d_{q'}(R_e(x))`，无安全转移则 −∞；`V_q={x∈Inv_q:d_q(x)≥0}`。`d≥1` 表示还有至少一条安全出路。

**定义 314（时间-承诺与截止时间松弛）** `τ_q(x)=inf{t:x(t)∉Inv_q}`（最佳可行性保持流下，保守估计）；`s_q(x,g)=τ_q−ℓ(g)−ε_r−τ_dec`；g 可行 ⇔ `s>0` 且执行后仍 `d≥d_min`。承诺集 `C_q={x: 无可行信息动作}`：在 C_q 中必须立即承诺。

**定义 315（HFP）** 离散模式头 `p_φ(σ|z,b)` + 模式条件速度场 `v_θ(x_s,s|z,σ,b)`；训练 `L_HFP=E‖v− (x_1−x_0)‖² − λ_ce log p_φ(σ_obs|z,b)`；采样 K 条混合计划，切换处施加 reset；执行前必须过 VCG 认证。

**定义 316–317（信息二分与 V-VoI）** `𝒜_info=𝒜_pass ⊔ 𝒜_act`；`g^act` 是模式转移，消耗逃生预算；`V-VoI(g)=D_q(x,g)·IG(g)−c_pass−c_irrev−c_risk`；`D_q=1` 仅当截止时间与逃生深度均满足；`V-VoI≤0` 或不安全则立即承诺。

**定义 318（MSC）** `A_safe={e=(q,q'): ∀q̃∈Q_ε(b), G_e 以裕度 δ_g 成立, R_e(x)∈V_{q̃}, d≥d_min, 兼作信息动作时 s>0}`；`e*=argmax[V_task+γV_escape−R−c]`；`A_safe=∅` 时只进 REE，绝不选未认证转移。

**定义 319（两级风险与非单调）** 连续层沿用 R69 λ，离散层用 `(q,e,b)` 与 `(d,s,margin)`；`k=min(k_R69,k_V,k_D)`；可行集 `Λ_safe(x)=[λ_min(τ),λ_max(U)]`；λ 过小会错过必须迈步的时刻，故「不确定只收紧」在混合系统中不成立；正确对象是 `(λ,模式,承诺时刻)` 三元组。

**定义 320（MCR）** 残差：invariant 裕度、guard innovation、dwell-time、跨通道模式分歧；`Λ_t>τ_conf` 或 ECE_mode 越界 ⇒ 冻结模式转移、扩张 ε-支持、缩短 k、只允许鲁棒/恢复模式。它是离散层的 FMA/CIA。

**定义 321（REE）** 预认证恢复集 R、策略 π_rec、恢复时间 t_rec、成功率 p_rec、损害上界 ε_rec；逃生预算 `ρ=d_q(x)`；`ρ≥ρ_min` 硬约束；`ρ<ρ_min` 禁主动探针；`ρ=0` 执行恢复。REE 是 λ_floor 的离散对应物。

**定义 322–323（机器认证与威胁模型）** `h_H=Hash(Q,E,Inv,G,R,Θ_G,VCG,REE)`；实时层零结构改写；负载/足端/地面变化触发离线重认证。`ℰ_STANCE=ℰ_FLUID×ℰ_mode×ℰ_machine`：接触欺骗、打滑、guard 投毒、状态机陈旧、可行性核投毒、延迟攻击、交互期推搡。

**定义 324（J_STANCE）** `Valid ⇔ Valid(J_FLUID) ∧ ECE_mode≤τ_ece ∧ margin≥0 ∧ d≥d_min ∧ s>0 ∧ 所有转移∈A_safe ∧ h_H 匹配 ∧ REE 非空`。

**定义 325（双速率契约）** 1 kHz 快速安全盾 <0.25ms；200 Hz 监督器 <0.9ms；50–100 Hz 混合流规划器 <3.5ms；规划器超时即保持上一已认证承诺或恢复，超时本身按模式混淆事件处理。

**定义 326（条件化 resolution bonus）** R69 的 bonus 仅在四条件同时满足时生效：信息在 τ 前完成、ECE_mode 在界内、消解后 d≥d_min、无 MCR 告警；否则按 `U_ale+U_epi` 处理并保持模式级鲁棒承诺。

## 3. 关键算法伪代码

```python
# IP-264/265 HSM + MBE：混合模式信念
class HybridModeBelief:
    def update(self, b, x, u, y):
        b = normalize(self.hsm.transition_prior(b, u) * self.contact_likelihood(y, x))
        return b, entropy(b), self.eps_support(b, EPS_MODE)

# IP-266 VCG：可行性核 / 逃生深度（离线预计算，在线 O(1) 查表）
def viable(x, q, b, grid):
    if min(invariant_margin(x, q), guard_margin(x, q)) < DELTA_G:
        return False, -1
    dest = [grid.depth(q2, reset(x, q, q2)) for q2 in grid.enabled(x, q, b)]
    d = 1 + max(dest, default=-1)
    return d >= D_MIN, d

# IP-267 CDS：截止时间门
def deadline_slack(x, q, g, grid):
    return grid.time_to_commit(x, q) - latency(g) - RESP_SLACK - REACT_TIME

# IP-268/269 HFP + V2I：混合计划采样 + 可行性门控 VoI
def plan_and_gate(policy, b, x, budget):
    plans = policy.sample_hybrid(x, b, K=adaptive_K(b))
    best = None
    for g in info_candidates(plans, support(b, EPS_MODE)):
        if not budget.allow(g) or deadline_slack(x, q_hat, g, VCG) <= 0:
            continue
        if not preserves_depth(g, x, b, VCG):          # 问完没退路
            continue
        score = info_gain(b, g) - cost(g) - irrev_cost(g) - risk(g)
        if score > 0 and (best is None or score > best.score):
            best = (g, score)
    return ("INFO", best[0], plans) if best else ("COMMIT", supervisor_choose(plans, b, x), plans)

# IP-270 MSC：对 ε-支持取最坏情况的鲁棒安全转移
def supervisor_choose(plans, b, x):
    cand = []
    for e in transitions(x, q_hat):
        if all(guard_ok(e, x, q2, DELTA_G) and
               reset_in_kernel(e, x, q2) and
               depth_after(e, x, q2) >= D_MIN
               for q2 in support(b, EPS_MODE)):
            cand.append((e, value(e, plans) - risk(e) + GAMMA * escape_value(e)))
    return max(cand, key=lambda z: z[1])[0] if cand else ("RECOVER", recovery_policy(x))

# IP-275 主闭环
def STANCE_round(M, obs):
    b, Hb, Qeps = M.mbe.update(M.b, M.x, M.u, obs)
    z, o = M.mtm.forward(obs); c, U_cal, thr = M.cof.step(...)
    samples = M.hfp.sample_hybrid(o, b, K=adaptive_K(b))
    U_ale, U_epi, modes, _ = M.aud.decompose(samples, z)
    conf = M.mcr.score(obs, b, M.hsm)
    if conf > TAU_CONF or Hb > TAU_MODE:
        e = M.ree.enter_robust(M.x, Qeps)
        return M.shield.commit(e, lam=M.lam_safe, k=M.k_safe)
    action, target, plans = M.v2i.plan_and_gate(b, M.x, M.budget)
    if action == "INFO":
        target = M.msc.execute_info(target, b, M.x)
        b, Hb, Qeps = M.mbe.update(b, M.x, M.u, obs)
        U_epi = M.cia.update_belief(modes, target)
        if not M.vcg.viable(M.x, q_hat, b)[0]:
            target = M.msc.robust_commit(plans, b, M.x)
    else:
        target = M.msc.choose(target, b, M.x)
    bonus = (action == "INFO" and Hb <= TAU_MODE and M.mcr.ok())
    U_floor = U_ale + (0.0 if bonus else U_epi)
    lam = M.efs.clip_to_viability(max(M.efs.risk_scale(...), lam_floor(U_floor)), M.x, q_hat)
    k = min(M.pi_sigma.prefix_dispatch(target.a), M.vcg.horizon(M.x, q_hat), M.cds.horizon(M.x, q_hat))
    M.j_stance.submit(b, Hb, target, lam, k, conf)
    return M.shield.commit(target, lam, k)             # 1 kHz：查表 + 解析 guard
```

## 4. 推导

**引理 19（截止时间对 VoI 的截断）** 若 `ℓ(g)+ε_r ≥ τ_q(x)`，则等待 g 的期望风险不低于立即承诺，且 `V-VoI(g)=0`；一般地有效信息增益 ≤ `1[τ_q>ℓ+ε_r]·ΔH`，且等待期间 `V_q(x(t))⊆V_q(x(0))`。系：R69 的 VoI 是 `τ=∞` 的退化；双足上「再等一帧」同时损失信息时效与退路。

**引理 20（无死锁承诺的归纳安全性）** 若每次承诺 e 对所有 `q̃∈Q_ε(b)` 都有 `R_e(x)∈V_{q̃}`、`d_{q̃}(R_e(x))≥d_min`、guard 裕度 ≥δ_g，则逃生深度每次至多减 1，最多 d_min 次承诺可达恢复集，期间不进入死端。证明：对承诺次数归纳，用 V 的不动点定义与 guard 鲁棒性。

**引理 21（模式辨识与可行性的时间权衡）** 相邻接触模式的 Chernoff 信息为 D 时，观测 T 后模式错误概率 ≤ `exp(−T·D)`；但同一 T 使可用承诺时间降为 `τ_q−T`。故 `R(T)≲exp(−T·D)+P_fall(τ_q−T)`，对 T 求导得最优 `T*`；当 `τ_q−T ≤ ℓ+ε_r` 时 `T*=0`。系：「多看一眼」的价值随剩余时间指数衰减，单脚支撑末期最优策略往往是迈而不是看。

**引理 22（主动探针的逃生预算守恒）** 任何 `g^act` 对应一次模式转移 `e_probe`，故 `ρ_after ≤ ρ_before − 1`；若 `ρ_before=ρ_min`，任何主动探针都不可采纳，只能被动观测或立即承诺。系：双足上「踩一脚试试」与「走一步」在资源账本上同类，不能当作 R69 的廉价 g。

**定理 18（STANCE 严格包含 R69）** 在 `|Q|=1、τ=∞、𝒜_act=∅、信息可逆、ECE_mode→0` 的退化机上，`A_safe` 退化为全部动作，`V-VoI` 退化为 R69 VoI，二者逐指令一致；R68 再作为 R69 的永不交互边界。反之，存在双足状态使 R69 的等待消歧必然错过截止时间而跌倒，STANCE 通过截止时间门选择立即承诺而避免。故安全侧不弱于 R69，且在有时限的混合系统中严格更强。

**定理 19（混合安全证书）** 在 A99–A103 下（可行性核保守、guard 认证、模式信念校准、MCR 阈值有效、恢复包络非空），STANCE 以概率 ≥`1−δ_total` 不执行未认证转移，`δ_total=δ_machine+δ_belief+δ_guard+δ_monitor`；若 `A_safe=∅` 则进入 REE，损害 ≤ε_rec；模式内连续层仍保持 R69 的 λ_floor 安全界。证明：离散层用引理 20 的归纳不变量，连续层用 R69 定理 16–17，二者只在已认证转移处耦合。

**定理 20（保守性的非单调——对 R69 的正面反驳）** 存在状态使 R69 的单调保守化（U↑ ⇒ 步长↓）严格增大跌倒概率：单脚支撑末期必须迈出至少 `l_min` 的一步才能把捕获点拉回下一支撑域，保守化把步长压到 `l_min` 以下反而越界。更一般地，可行 λ 集是区间 `Λ_safe(x)=[λ_min(τ),λ_max(U)]`；区间为空时唯一正确动作是切换恢复模式，而不是继续降低 λ。故「不确定→只收紧」在混合系统中不成立；正确偏序是 `(λ,模式,承诺时刻)` 三元组偏序。系：状态机不是给 R69 再加一层刹车，而是给它一套「什么时候必须踩油门」的规则。

## 7. 本轮最大风险

**一句话**：STANCE 把安全从「连续地慢下来」变成「离散地进入一个已被认证的模式」；**状态机、guard 与可行性核只是模型，一旦它们有偏、陈旧或被投毒，系统会带着一张看似完备的证书走进死胡同——离散的假安全比连续的保守更致命，因为前者会主动取消后者本来提供的退路。**

**次级风险与缓解**：模式混淆（MBE 多通道 + MCR + ECE_mode 门控）；可行性核过保守（离线核 + 在线 margin + E314 Pareto）；主动探针耗尽逃生预算（引理 22，ρ<ρ_min 禁用）；截止时间估计偏差（保守 τ + 双速率盾 + 超时即恢复）；状态机陈旧（machine_hash + 离线重认证 + 零在线结构改写）；guard 投毒/假安全证书（ℰ_STANCE 对抗训练 + E306/E307 + 模型版本审计）。
