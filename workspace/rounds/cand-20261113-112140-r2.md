# 第 66 轮（承接第 65 轮「VISTA 故障可归因安全时序」IP-214~223；灵感循环第 2 轮；本轮灵感：「可用性评估」×「评测基准」）

> 第 65 轮把「几何可证伪」升级为「故障可归因」，用视觉、动作分块与主动判别探针把「谁坏了」从不可辨识变成可分离，并用「长预测、短执行」把块级承诺压回不可逆视界。它自述的最大风险是：**归因依赖「故障属于有限假设集、且视觉与几何失效相互独立」两个隐藏假设；未知复合故障与共因失效会让 FIR 把「未知」强行归入最近假设、只膨胀错误的球，而系统因「已经归因」而更自信地继续执行（A88）。** 本轮不往系统里再塞第六个模态，也不把故障假设集再扩大一格，而是把镜头从「系统内部」转到「系统的两个外部评估接口」：**在屏幕前做决定的人，和用来证明系统有效的基准。**
>
> 核心命题：**把「故障可归因」升级为「评估可审计、证书可决策」——把安全证书编译成「决策充分」的人可操作卡，把评测基准本身当作需要认证的测量仪器，并把「内部置信 / 基准分数 / 人的信念 / 部署真值」之间的不一致定义为一等安全信号「评测差距」；当基准不可信、操作者不可用、或两者同时失效时，系统必须退到已知安全模式，而不是继续自信执行。**

## 0. 直觉与动机

**灵感 1（可用性评估 → 证书不是日志，而是决策接口）**
直觉：J_vista 是一个十多个字段的元组，机器能验证，人却无法在几百毫秒内使用。第 65 轮的安全论证在「机器证书」处戛然而止，默认「人看到证书就会做出正确决定」。但真实部署里，人恰恰是最后一道安全环节：继续 / 接管 / 急停。若证书没有把「最可能的故障、现在最安全的一组动作、什么新证据会改变结论、我有多确定、这个结论是否值得信」压缩到人的工作记忆里，人就会用错误的方式使用它——**自动化偏置**让人在机器说「已归因」时过度接受，**告警疲劳**让人在反复告警后忽略真正的危险。因此可用性评估不是 SUS 问卷，而是**决策质量**：在时间压力下，人能否以足够小的后悔做出正确动作。

**灵感 2（评测基准 → 基准是带偏差的测量仪器，而不是真值）**
直觉：第 65 轮报告「归因准确率 ≥90%、误降级 −60%」，但这些数字只和**基准**一样可信。基准有构造效度问题（测的是不是我们声称的能力）、污染与泄漏（测试场景进了训练集）、Goodhart / 基准黑客（策略专门刷分却不会部署）、以及仿真到现实的分布漂移。一个只包含「容易负例」的基准，会让一个**遇到未知故障就过度自信**的系统拿到高分——恰好奖励了第 65 轮最危险的失效模式。因此对基准必须做**元评估**：先认证测量仪器，再相信测量结果；并用「元基准红队」主动搜索「置信度高但实际不安全」的场景。

**灵感 3（合流 → 评估器也是系统的一部分，评测差距是一等信号）**
直觉：人是一个评估器，基准也是一个评估器；两者都会错，且两者都可能被「优化」。与其分别修补，不如把**三方的分歧**本身当作传感器：机器内部置信度、基准分数、操作者信念，三者与部署真值的偏差构成**评测差距 G**。当 G 很小，证书可信；当 G 很大且方向是「置信度高于真实安全」，这本身就是一种新故障假设 **H_eval（评估器坏了）**，应当像 H_geo / H_force 一样被归因、被处置。这把第 65 轮的「过度自信」从一个只能事后复盘的现象，变成可在运行时监测、可被证书拒绝的信号。

**灵感 4（合流 → LUCID：Legible, Usable Certificates with Independent benchmark valiDity，可读可用的证书 × 独立有效的基准）**
直觉：LUCID 闭环 = VISTA → 决策卡生成（DCG）→ 操作者模型与信任校准（OPM/CTC）→ 可用性证书（UEC）→ 基准有效性证书（BVC）→ 元基准红队（MBR）→ 评测差距监控（EGD）→ 评测感知证书（J_lucid）→ 评估不可用时的安全降级。核心原则是：**一个安全声明的强度，不会超过它最弱的那个评估器。** 第 65 轮是「几何-技能-干扰-接触-归因」五层；LUCID 增加「**评估层**」（人 + 基准），并让这一层也受同一张证书约束。

**灵感 5（VISTA 组件的原位升级）**
- **FIR → FIR-U**：后验之外增加「决策相关裕度」与「反事实证据」——不仅说「谁最可能坏」，还说「什么证据会翻转这个结论」。
- **DCG（新）**：把 J_vista 投影为最简决策卡；用率失真/信息瓶颈求「足够短又足够全」的表示。
- **OPM/CTC（新）**：显式建模人的信念、信任与偏置；用信任校准误差驱动呈现粒度。
- **UEC（新）**：可用性 = 决策后悔、正确决策时间、过/欠信任率、告警精确率、工作负荷。
- **BVC（新）**：基准有效性 = 构造覆盖、污染度、统计功效、对抗覆盖、漂移覆盖，并给出误差上界。
- **MBR（新）**：元基准红队，主动最大化「置信度 − 实际安全」或「基准分 − 部署表现」。
- **CSC → CSC-U**：认证前缀同时受不可逆视界 m 与人的反应时间约束：`k*·Δt + t_render + T_react ≤ t_stop`。
- **RSC-V → RSC-E**：不确定球增 `r_eval`（评测效度不确定）与 `r_human`（操作者模型不确定），只在对应证据出现时膨胀。
- **AIC-V → AIC-U**：干扰集增「基准黑客 / 污染 / 构造效度错配」与「人类因素攻击（告警洪水、误导性解释、信任操纵）」。
- **J_vista → J_lucid**：证书增 `usability_cert`、`operator_belief`、`benchmark_validity_cert`、`evaluation_gap`、`evaluability_status`、`mbr_ver`、`ctc_ver`。
- **OLP / DIR / SSB**：人机交互日志与基准元数据只在语义流；实时流只做决策卡渲染、硬约束守卫、降级触发。

## 1. 形式化定义（增量：定义 233–248）

- **定义 233（LUCID 闭环）**：LUCID = (VISTA, DCG, OPM, UEC, BVC, MBR, EGD, CTC, J_lucid)。定位：VISTA 的「评估外部性」升级。不变式：**可用性建模、基准认证、红队搜索、信任校准只在语义流；实时流只做决策卡渲染、硬约束守卫、评估不可用降级，零学习写操作。**
- **定义 234（决策就绪证书 DC）**：DC = (h_top, margin, SafeSet, Δ_evidence, confidence, evaluability)，是 J_vista 面向人的投影；Δ_evidence 为「会翻转结论的最小新证据」。
- **定义 235（决策充分性）**：对解释 E（状态 S 的函数），`d(E)=max_a |Q*(a|S) − Q_E(a|E)|`；若 `d(E)≤ε` 且除概率 ≤δ 的状态外最优动作一致，称 (ε,δ)-决策充分。最简卡 `E* = argmin_{E: d(E)≤ε} I(S;E)`（信息瓶颈 / 率失真）。
- **定义 236（操作者模型 OPM）**：人持有对系统可靠性的信念 b 与信任 τ，观察 DC，按 π_H(DC,b,τ,t) 动作；含自动化偏置 β_ab、告警疲劳 λ_af、反应时间 T_react 分布。人因此是被认证的**联合系统部件**。
- **定义 237（可用性证书 UEC）**：U=(R_dec,T_dec,OT,UT,AP,WL)（决策后悔、正确决策时间、过度信任率、信任不足率、告警精确率、工作负荷）。认证条件：`R_dec≤ε_u`、`OT≤η_ot`、`UT≤η_ut`、`T_dec·v≤d_stop`。
- **定义 238（基准有效性证书 BVC）**：BVC=(C_con,ρ_cont,P_pow,C_adv,C_shift)，并给出统计保证：对漂移族 𝒮 中任意部署分布，`P(|Ŝ_bench−S_deploy|≤ε_b)≥1−δ_b`；误差分解为构造偏差、采样方差、污染项与漂移项。
- **定义 239（基准作为假设 / 构造效度）**：基准 B 是一条测量假设；构造效度要求「名义网络」：B 与目标能力的独立测量相关、与无关混淆变量不相关；并要求阳性对照与阴性对照（能分开「有能力/无能力」）。
- **定义 240（评测差距 EGD）**：`G=(CE_int,VE,TE)`，分别度量内部置信、基准分数、人的信念相对部署真值的偏差；标量 `G=max` 或加权和；有向版本 `G⁺=max(0,conf−Safety)` 专门捕捉过度自信。`G⁺>τ_g` 触发新假设 H_eval。
- **定义 241（元基准红队 MBR）**：在场景空间搜索 `ξ*=argmax_ξ [conf_sys(ξ)−Safety(ξ)]` 或 `|score_B(ξ)−Safety(ξ)|`，返回「证书证伪集」。它是第 65 轮「过度自信」风险的直接对抗测试。
- **定义 242（信任校准 CTC）**：`ECE_trust=Σ_bin |P(safe|trust bin)−trust|`；控制器在 `{minimal,standard,detailed,evidence_request}` 中选择呈现粒度，最小化 `ECE_trust+λ_wl·WL` s.t. 决策充分。
- **定义 243（评估不可用与安全降级）**：`e∈{evaluable,bench_invalid,op_overloaded,both_invalid}`；映射到安全模式：基准失效→硬包络主导的慢速自主；操作者过载→降细节 + 自动安全停 + 求助；两者失效→保守撤退并显式声明「无法认证」。
- **定义 244（人机联合安全）**：联合系统 (robot, operator) 在对可达信念集 B、任意 `T_react≤T_max` 下安全，当且仅当人的动作保持状态在 SafeSet，或机器人硬包络在越界前接管。
- **定义 245（J_lucid）**：`J_lucid=(J_vista,usability_cert,operator_belief,benchmark_validity_cert,evaluation_gap,evaluability_status,mbr_ver,ctc_ver)`。Valid 需 J_vista 有效 ∧ UEC 有效 ∧ BVC 在当前漂移类上有效 ∧ `evaluability_status≠both_invalid` ∧ MBR 覆盖过度自信场景。
- **定义 246（评估预算与评测信息价值）**：在评测预算下选择下一次测试/用户实验 `argmax E[ΔG]/cost`，把「该跑哪个基准、该做哪次可用性实验」也变成可优化问题。
- **定义 247（基准污染与泄漏）**：`ρ_cont` 来自近重复重叠、成员推断与测试到训练泄漏；`ρ_cont>τ_c` 时 BVC 失效。
- **定义 248（评估不可能三角）**：以下三者不能同时成立：(i) 部署保真（基准≈漂移下的真值）；(ii) 低评测成本；(iii) 抗 Goodhart。廉价基准必是低维摘要，低维摘要必可被博弈；要不可博弈就需接近部署的丰富度，成本必然上升。

## 2. 关键算法骨架

```python
# DCG：把机器证书投影为决策卡（语义流）
dc = dcg.compress(j_vista, state, eps=0.05)      # min I(S;E) s.t. d(E)<=eps
assert argmax_action(dc) == argmax_action(full_state)

# OPM + CTC：信任校准决定呈现粒度
tau = opm.update(operator_history, outcomes)
level = ctc.choose_granularity(tau, workload, dc)  # minimal/standard/detailed/evidence_request
render(dc, level=level)

# BVC + MBR：先认证基准，再用它评估
bvc = benchmark_validity.certify(bench, shift_family=S)
if not bvc.valid:
    evaluability = 'bench_invalid'
ambush = mbr.search(argmax=lambda xi: conf_sys(xi) - safety(xi))
bench = bench.augment(ambush)                     # 用"打脸集"补基准

# EGD：评测差距作为新故障假设
g_plus = max(0.0, conf_internal - deployment_safety_estimate)
if g_plus > TAU_G:
    post['H_eval'] = max(post['H_eval'], posterior_from_gap(g_plus))
```

## 3. 保证概要与推导要点（完整推导见产物区）

- **引理 13（决策充分性保动作）**：若决策卡 (ε,δ)-决策充分，且操作者决策规则相对卡片 ε_H-最优，则人机联合后悔 ≤ ε + ε_H + δ·Q_max；当安全裕度 margin>ε+ε_H 时，卡片不会把安全动作翻成不安全动作。
- **引理 14（基准有效性误差界）**：`|Ŝ_B−S_deploy| ≤ bias_con + ρ_cont·L + √(Var/(2n)·log(2/δ)) + shift_term`（Bernstein + conformal + 污染项）。因此「基准高分」只有在 BVC 有效时才能当作安全证据。
- **引理 15（信任校准的人机安全）**：在 ECE_trust≤η 且 `T_react≤T_max` 下，过度信任导致的不安全接受概率 ≤ η+η_ot；机器人硬包络覆盖剩余事件。故人机联合安全可由 UEC + 硬包络共同保证。
- **定理 11（LUCID 端到端：评估错误下的安全）**：在 A101–A106 下，Valid(J_lucid) ⇒ (i) 归因错误只影响性能、不越出硬包络；(ii) 基准数字在当前漂移类上可信；(iii) 操作者决策质量被证书约束；(iv) 当任一评估器失效时系统显式降级到已知安全模式。证书链从「几何-技能-干扰-接触-归因」扩为「…-归因-评估」。
- **定理 12（评估不可能三角）**：廉价基准是低维摘要；任何低维摘要都存在一个在摘要上最优、在部署上失败的策略（Goodhart）；要让摘要不可被博弈，必须让其维度/场景覆盖接近部署，评测成本随之上升。故三者至多同时满足两项。
- **命题（评测差距是前兆）**：`G⁺` 在多数故障前先上升（置信先于后果脱节），故可作早期预警；以 `G⁺` 为监控量可比事后指标提前 τ_lead 发现过度自信。
- **实时性**：DCG 渲染、硬守卫、降级触发在实时流；OPM/CTC/BVC/MBR/EGD 全在语义流，目标实时路径 ≤2.6ms。

## 5. 本轮最大风险

**一句话**：LUCID 的最大风险是**评估的无限回退与「审计剧场」**——可用性证书与基准有效性证书本身也是被测量出来的，而测量它们的人/基准同样会错；一旦 BVC 在「被优化」的基准上自证有效、UEC 在「被挑选」的受试者上自证可用，系统就获得了一张看起来更完备、实则把「谁评估评估者」这一回退藏得更深的证书：**第 65 轮的「错误归因 + 过度自信」由此升级为「错误评估 + 审计合规式自信」**（A101）。

## 2. 形式化定义（完整版）

**定义 233（LUCID 闭环）** LUCID 是 VISTA 的「评估外部性」升级：在 VISTA 的「语义流 ∘ 实时流」骨架上挂载 DCG（决策卡）、OPM/CTC（操作者模型与信任校准）、UEC（可用性证书）、BVC（基准有效性证书）、MBR（元基准红队）、EGD（评测差距监控），并原位升级 FIR→FIR-U、CSC→CSC-U、RSC-V→RSC-E、AIC-V→AIC-U、J_vista→J_lucid。不变式：**可用性建模、基准认证、红队搜索、信任校准、评测差距计算只发生在语义流；实时路径只做卡片渲染、硬约束守卫、评估不可用降级与派发，零学习写操作。**

**定义 234（决策就绪证书 DC）** 给定 J_vista 与当前状态 S，DC 是一个面向人的投影：
`DC=(h_top, margin, SafeSet, Δ_evidence, confidence, evaluability)`，
其中 h_top 为最可能故障假设，margin 为最可能假设与次优假设的后验差，SafeSet 为在当前归因后验支持集上仍安全的动作/前缀集合，Δ_evidence 为「会翻转当前最优动作的最小新证据」，confidence 为校准后的置信度，evaluability 为当前评估器是否可信。DC 是 J_vista 的**有损压缩**，但必须是**决策保持**的。

**定义 235（决策充分性）** 设全状态 S、动作价值 Q*(a|S)，解释 E 为 S 的函数，卡片条件价值 Q_E(a|E)。定义最坏决策失真
`d(E)=max_a |Q*(a|S) − Q_E(a|E)|`。
若 `d(E)≤ε`，且除总概率 ≤δ 的状态外 `argmax_a Q*(a|S)=argmax_a Q_E(a|E)`，称 E 为 (ε,δ)-决策充分。最简卡为率失真/信息瓶颈问题
`E* = argmin_{E: d(E)≤ε} I(S;E)`。
直觉：**卡片要短到能读，又要全到不改变安全动作**。字段数不是目标，决策失真才是。

**定义 236（操作者模型 OPM）** 操作者持有对系统可靠性的信念 b 与信任水平 τ∈[0,1]，观察决策卡 DC，按策略 π_H(DC,b,τ,t) 选择动作（继续/接管/急停/追问）。已知偏置显式建模：自动化偏置 β_ab（机器高置信时人过度接受其建议）、告警疲劳 λ_af（重复告警后响应强度衰减）、反应时间 T_react∼P_react。信念更新 `b' = B(b, outcome, alarm)`。人因此不是外部审计者，而是**被证书约束的联合系统部件**。

**定义 237（可用性证书 UEC）** `U=(R_dec,T_dec,OT,UT,AP,WL)`：
- R_dec：相对全状态最优动作的决策后悔；
- T_dec：从告警到做出正确动作的时间；
- OT：过度信任率（接受机器的不安全建议）；
- UT：信任不足率（拒绝机器的安全建议）；
- AP：告警精确率（真异常/全部告警）；
- WL：操作者工作负荷。
认证条件：`R_dec≤ε_u`、`OT≤η_ot`、`UT≤η_ut`、`T_dec·v≤d_stop`。**可用性不是主观满意度，而是可测的决策质量。**

**定义 238（基准有效性证书 BVC）** `BVC=(C_con,ρ_cont,P_pow,C_adv,C_shift)`：
- C_con：构造覆盖（每个声称能力是否有阳性/阴性对照）；
- ρ_cont：污染/泄漏度；
- P_pow：统计功效（区分目标效应所需样本）；
- C_adv：对抗覆盖（是否含基准黑客、对抗 patch、共因故障）；
- C_shift：漂移覆盖（评测场景与部署分布差异的界定）。
有效性要求：对漂移族 𝒮 中任意部署分布 P_deploy，
`P(|Ŝ_bench − S_deploy| ≤ ε_b) ≥ 1−δ_b`。
误差分解见引理 14。**基准不是真值，是被认证过的测量仪器。**

**定义 239（基准作为假设 / 构造效度）** 基准 B 本身是一条测量假设。构造效度要求「名义网络」：(i) B 的分数与目标能力的**独立**测量相关；(ii) B 与无关混淆变量（渲染风格、场景长度、物体颜色、动作平滑度）不相关；(iii) B 能通过阳性对照（有该能力的策略高分）与阴性对照（故意缺失该能力的策略低分）。若阴性对照也能拿高分，则 B 测的不是该能力，而是别的捷径。

**定义 240（评测差距 EGD）** 定义向量
`G=(CE_int, VE, TE)`，
其中 `CE_int=d(conf_internal, Safety)`、`VE=|Ŝ_bench−S_deploy|`、`TE=d(belief_operator, Reliability)`。标量取 `G=max` 或加权和；有向过度自信量
`G⁺ = max(0, conf_internal − Safety)`。
当 `G⁺>τ_g` 时，不把它当作噪声，而是注入新故障假设 H_eval（评估器坏了），进入 FIR-U。这把「过度自信」从事后复盘指标变成运行时可归因信号。

**定义 241（元基准红队 MBR）** 在场景空间 Ξ 上求解
`ξ* = argmax_{ξ∈Ξ} [ conf_sys(ξ) − Safety(ξ) ]`
或 `argmax_ξ |score_B(ξ) − Safety(xi)|`，
返回证伪集 `F_B={ξ*}`。MBR 可以内层让策略最大化基准分、外层搜索基准分与真实安全差距（双层优化），从而主动构造「刷分但不安全」与「高置信但翻车」的场景。它是第 65 轮「过度自信」风险的直接对抗测试。

**定义 242（信任校准 CTC）** 信任校准误差
`ECE_trust = Σ_{bin} | P(safe | τ∈bin) − τ̄_bin |`。
控制器在呈现粒度 `L∈{minimal, standard, detailed, evidence_request}` 中选择
`L* = argmin_L [ ECE_trust(L) + λ_wl·WL(L) ]`
s.t. 卡片在此粒度下 (ε,δ)-决策充分。当人过信任时增加「不确定性/反事实证据」，当人欠信任时减少噪声并突出已验证的安全裕度。**呈现不是美化，是闭环控制。**

**定义 243（评估不可用与安全降级）** 评估可用性状态
`e∈{evaluable, bench_invalid, op_overloaded, both_invalid}`。
降级映射：
- `bench_invalid`：不采信基准数字，退回硬包络主导的慢速自主，置 `evaluation_gap.valid=False`；
- `op_overloaded`：降细节、自动安全停、发出求助，禁止要求人在 `T_react` 内处理复杂卡片；
- `both_invalid`：保守撤退 + 显式声明「无法认证」，只执行经硬包络验证的 `safe_idle`。

**定义 244（人机联合安全）** 联合系统 (robot, operator) 在可达信念集 `B`、任意 `T_react≤T_max` 下安全，当且仅当对任意 `b∈B` 与任意延迟，人的动作 `a_H` 使状态保持在 SafeSet，**或**机器人硬包络在越界前接管。形式化：
`∀b∈B, ∀t_react≤T_max: Reach(s, π_H(DC,b), t_react) ⊆ SafeSet ∨ HardEnvelope(s)=1`。
这把「人」纳入与 VISTA 相同的安全论证，而不是假设人永远正确。

**定义 245（LUCID 证书 J_lucid）** `J_lucid=(J_vista, usability_cert, operator_belief, benchmark_validity_cert, evaluation_gap, evaluability_status, mbr_ver, ctc_ver)`。验证规则：
`Valid(J_lucid) ⇔ Valid(J_vista)`
`∧ UEC 达标 ∧ BVC 在当前漂移类上有效`
`∧ evaluability_status ≠ both_invalid`
`∧ MBR 的证伪集已被基准吸收或显式计入 G⁺`
`∧ 卡片与其呈现粒度满足决策充分`
`∧ mbr_ver/ctc_ver 为当前版本`。
审计链新增：为什么这张卡能让人安全决策（UEC）、这个基准凭什么可信（BVC）、置信与真值的差距（G）、评估器失效时做了什么（evaluability_status）。

**定义 246（评估预算与评测信息价值）** 给定评测预算 `B_eval`，选择下一项评测 `q`（跑哪个基准、做哪次用户实验、注入哪类红队场景）：
`q* = argmax_q E[ΔG(q)] / cost(q)`
s.t. `Σ cost(q)≤B_eval`。这把「该测什么」从经验选择变成期望信息价值问题；与第 65 轮 AFA 的「探针选哪个」同构，只是探针变成了评测。

**定义 247（基准污染与泄漏）** 污染度
`ρ_cont = max( near_dup_overlap, membership_inference_gain, test_to_train_leakage )`。
当 `ρ_cont>τ_c` 时 BVC 失效；此时的基准高分不能作为安全证据，只能作为「可疑」信号写入 J_lucid。

**定义 248（评估不可能三角）** 对任意基准 B，以下三者不能同时成立：
1. **部署保真**：`∀π`，`|score_B(π) − J_deploy(π)| ≤ ε`；
2. **低评测成本**：`cost(B)=o(|Π|)`（远小于策略/场景空间）；
3. **抗 Goodhart**：不存在 `π` 使 `score_B(π)` 高而 `J_deploy(π)` 低。
直觉：低成本基准必是策略/场景空间的低维摘要；低维摘要的等值面很大，总能找到在其上最优、在部署上失败的策略；要让等值面不可被利用，基准必须对相关行为近似单射，成本随之接近部署。**评估不是免费的午餐；LUCID 的贡献是把这项取舍显式化、可审计化，而不是假装消除它。**

### IP-224 DCG（决策就绪证书）

```python
class DecisionCardGenerator:
    def __init__(self, eps=0.05, delta=0.01, max_fields=6):
        self.eps, self.delta, self.max_fields = eps, delta, max_fields

    def compress(self, j_vista, state, post, safe_evaluator):
        # 候选投影：按"对最优动作的影响"贪心保留字段
        fields = [('h_top', top_hypothesis(post)),
                  ('margin', posterior_margin(post)),
                  ('SafeSet', safe_evaluator.safe_set(post)),
                  ('confidence', calibrate(confidence(post))),
                  ('evaluability', j_vista.evaluability_status)]
        card = {}
        for name, val in fields:
            card[name] = val
            if decision_distortion(card, state) <= self.eps:
                break                                    # 已决策充分，停止加字段
        if decision_distortion(card, state) > self.eps:
            card['delta_evidence'] = self._flip_evidence(state, post)
        card['delta_evidence'] = card.get(
            'delta_evidence', self._minimal_flip(state, post))
        assert decision_distortion(card, state) <= self.eps + 1e-9
        return card

    def _minimal_flip(self, state, post):
        # 找到使 argmax 翻转的最小证据方向（信息价值最大处）
        h1, h2 = top_two(post)
        return {'evidence': 'probe distinguishes %s vs %s' % (h1, h2),
                'expected_gain': expected_value_of_information(post, h1, h2)}

    def _flip_evidence(self, state, post):
        return self._minimal_flip(state, post)
```

### IP-225 OPM / CTC（操作者模型与信任校准）

```python
class OperatorModel:
    def __init__(self, beta_ab=0.2, lam_af=0.1, t_react_max=1.2):
        self.beta_ab, self.lam_af, self.t_react_max = beta_ab, lam_af, t_react_max
        self.belief = 0.9          # 对系统可靠性的先验信念
        self.trust = 0.9
        self.alarm_count = 0

    def update(self, outcome, alarm):
        self.alarm_count = self.alarm_count + 1 if alarm else 0
        fatigue = 1.0 - self.lam_af * min(1.0, self.alarm_count / 10.0)
        self.belief = bayes_update(self.belief, outcome) * fatigue
        self.trust = clip(self.trust + 0.05 * (outcome - 0.5), 0.0, 1.0)
        return self

    def predict_action(self, card, t_elapsed):
        if t_elapsed > self.t_react_max:
            return 'emergency_stop'          # 超时默认保守
        if card['confidence'] > 0.9:
            return 'accept' if self.belief * (1 + self.beta_ab) > 0.6 else 'hesitate'
        return 'request_evidence' if self.trust < 0.7 else 'accept'


class TrustCalibrator:
    LEVELS = ('minimal', 'standard', 'detailed', 'evidence_request')

    def choose(self, opm, workload, card):
        best, best_cost = 'standard', np.inf
        for level in self.LEVELS:
            rendered = render(card, level)
            ece = trust_calibration_error(opm.trust, rendered)
            cost = ece + LAMBDA_WL * workload_of(level)
            if cost < best_cost and decision_sufficient(rendered, card):
                best, best_cost = level, cost
        return best
```

class BenchmarkValidityCertificate:
    def certify(self, bench, shift_family, n, delta=0.05):
        c_con = construct_coverage(bench)            # 阳性/阴性对照是否齐全
        rho_cont = contamination(bench)              # 近重复/成员推断/泄漏
        p_pow = statistical_power(bench, n, delta)   # 能否分辨目标效应
        c_adv = adversarial_coverage(bench)          # 是否含黑客/对抗/共因
        c_shift = shift_bound(bench, shift_family)   # 漂移界
        lower = c_con * c_adv * (1 - rho_cont) * c_shift
        valid = (rho_cont <= TAU_C and lower >= L_MIN and p_pow >= P_MIN)
        return {'valid': valid, 'C_con': c_con, 'rho_cont': rho_cont,
                'P_pow': p_pow, 'C_adv': c_adv, 'C_shift': c_shift,
                'eps_b': error_bound(bench, n, rho_cont, c_shift, delta)}

### IP-228 MBR（元基准红队）

```python
class MetaBenchmarkRedTeam:
    def search(self, scenario_space, policy, n_iter=200):
        """外层找"高置信低安全"；内层让策略在当前基准上刷分。"""
        ambush = []
        for xi in scenario_space.sample(n_iter):
            policy_fast = policy.adapt_to_benchmark(xi)     # 内层：刷分
            conf = policy_fast.confidence(xi)
            safety = evaluate_deployment(policy_fast, xi)
            if conf - safety > TAU_AMBUSH:
                ambush.append((xi, conf, safety))
        return sorted(ambush, key=lambda z: z[1] - z[2], reverse=True)
```

### IP-233 LUCID 闭环算子（与 VISTA 整合）

```python
def LUCID_round(M, obs, delta_f_req):
    # ———— 语义流：先认证评估器，再谈安全 ————
    bvc = M.bvc.certify(M.bench, M.shift_family, M.n_eval)
    uec = M.uec.evaluate(M.operator_trials)            # 最近的用户实验/在线日志
    e_status = classify_evaluability(bvc, uec)

    M, K_safe, EV_exec, j_vista = VISTA_round(M, obs, delta_f_req)

    # 1) 决策卡：机器证书 → 人可操作卡
    dc = M.dcg.compress(j_vista, M.state, M.fir.post)
    level = M.ctc.choose(M.opm, M.workload, dc)
    M.render(dc, level)

    # 2) 评测差距：过度自信 → 新故障假设 H_eval
    g_plus = max(0.0, j_vista.confidence - M.deployment_safety_estimate)
    if g_plus > TAU_G:
        M.fir.post['H_eval'] = max(M.fir.post.get('H_eval', 0.0),
                                   posterior_from_gap(g_plus))
        M.balls['r_eval'] = min(R_MAX, KAPPA_EVAL * g_plus)

    # 3) 人的反应时间进入认证前缀
    k_star = M.csc_u.certified_prefix(
        M.tau.A, M.fir.post, M.m,
        t_stop=M.t_stop, t_render=M.t_render,
        t_react_max=M.opm.t_react_max, dt=M.dt)
    if k_star < 1:
        return M, M.safe_idle(), EV_exec, degrade(j_vista, 'op_overloaded')

    # 4) 评估失效时降级，而不是继续
    if e_status == 'both_invalid':
        return M, M.safe_idle(), EV_exec, degrade(j_vista, 'both_invalid')
    if e_status == 'bench_invalid':
        M.balls['r_eval'] = min(R_MAX, KAPPA_EVAL * M.balls.get('r_eval', 0.1))

    # 5) 元基准红队：持续找"高置信不安全"，补进基准
    ambush = M.mbr.search(M.scenario_space, M.policy, n_iter=M.n_mbr)
    M.bench = M.bench.augment(ambush)
    M.uec = M.uec.update_from_logs(M.interaction_log)

    j_lucid = build_j_lucid(j_vista, uec, M.opm.belief, bvc,
                            evaluation_gap=(g_plus, j_vista.confidence,
                                            M.deployment_safety_estimate),
                            evaluability_status=e_status,
                            mbr_ver=MBR_VERSION, ctc_ver=CTC_VERSION)
    return M, K_safe, EV_exec, j_lucid
```

### IP-231 CSC-U（把人的反应时间纳入认证前缀）

```python
def csc_u_prefix(A, post, m, t_stop, t_render, t_react_max, dt):
    # 不可逆视界 m 与"人来得及接管"共同限制前缀
    k_m = m
    k_h = int(math.floor((t_stop - t_render - t_react_max) / dt))
    k_max = min(k_m, k_h, len(A))
    for k in range(k_max, 0, -1):
        if all(safety_margin(A[s], h) >= 0
               for h in support(post) for s in range(k)):
            return k
    return 0                                     # 来不及 → safe_idle
```

### IP-232 RSC-E（评估感知的定向球）

```python
def rsc_e_update(balls, post, bvc, opm, g_plus):
    if not bvc['valid'] or g_plus > TAU_G:
        balls['r_eval'] = min(R_MAX, KAPPA_EVAL * max(balls.get('r_eval', R_MIN), R_MIN))
    if opm.uncertainty() > TAU_HUMAN:
        balls['r_human'] = min(R_MAX, KAPPA_HUMAN * opm.uncertainty())
    # 只膨胀被归因者；评估不确定性不触碰已标定的几何/力球
    fused = math.sqrt(sum(balls.get(k, 0.0) ** 2
                          for k in ('r_geo', 'r_force', 'r_model',
                                    'r_eval', 'r_human')))
    return balls, fused
```

## 4. 推导

**显式假设 A101–A106**
- **A101（元评估有效）**：BVC/UEC 的标定数据与部署同分布，或漂移可由 𝒮 界定。**这是本轮最深、也最危险的隐藏假设：评估器本身的可信度无法被同一套评估器完全证明。**
- **A102（硬包络独立）**：力限、碰撞、速度、关节限位由不依赖学习模型/评估器的实时控制器强制。
- **A103（人的上界）**：`T_react≤T_max`，且操作者语义覆盖基本告警类别（训练/说明书覆盖）。
- **A104（漂移可检测）**：漂移超出 𝒮 时，BVC 失效可被检测并触发降级。
- **A105（评测可交换性）**：在给定 shift 类内，conformal 的可交换性近似成立。
- **A106（安全真值可测）**：评测环境可独立测量部署安全，用于校准 G。

**引理 13（决策充分性保动作）** 设 `d(E)=max_a|Q*(a|S)−Q_E(a|E)|≤ε`，操作者相对卡片 ε_H-最优：`Q_E(a_H)≥max_aQ_E(a)−ε_H`。则
`Q*(a_H) ≥ Q_E(a_H)−ε ≥ max_aQ_E(a)−ε_H−ε ≥ max_aQ*(a)−2ε−ε_H`。
故联合后悔 `Regret≤2ε+ε_H`；对概率 ≤δ 的异常状态再加 `δ·Q_max`。若安全裕度 `margin>2ε+ε_H`，任何 ε_H-最优的卡片动作仍落在 SafeSet。因此「决策充分」是卡片可被人安全使用的最小条件，而不是「信息越多越好」。∎

**引理 14（基准有效性误差界）** 把误差拆为
`Ŝ_B−S_deploy = (Ŝ_B−S_B) + (S_B−S_deploy)`。
第一项为采样误差。损失有界于 [0,L]，由 Bernstein 不等式
`P(|Ŝ_B−S_B|≥t) ≤ 2exp(−nt²/(2σ²+Lt/3))`。
第二项为构造+漂移偏差。污染比例 ρ_cont 的最坏影响 ≤ρ_cont·L；漂移在 L-Lipschitz 度量下 ≤L·W1(P_B,P_deploy)，或由 conformal 分位数给出。合并得
`|Ŝ_B−S_deploy| ≤ ρ_cont·L + √(2σ²log(2/δ)/n) + L·log(2/δ)/(3n) + shift_term`。
因此「基准高分」只有在 BVC 的 ρ_cont、功效与漂移项都通过时，才有资格作为安全证据；否则只能进入 G。∎

**引理 15（信任校准的人机安全）** 设 `ECE_trust≤η`、过度信任率 `OT≤η_ot`，且 `T_react≤T_max`。过度信任导致的不安全接受事件是「τ 高但实际不安全」的错配，其概率被 `η+η_ot` 控制（校准误差 + 尾部）。再由 `T_react≤T_max` 与 CSC-U 的 `k*≤(t_stop−t_render−T_max)/Δt`，人在停止距离耗尽前有足够时间接管。剩余事件由 A102 硬包络覆盖。故人机联合安全由 UEC + CSC-U + 硬包络三者共同保证。∎

**定理 11（LUCID 端到端：评估错误下的安全）** 在 A101–A106 下，若 `Valid(J_lucid)`，则：
1. **归因错误不越硬界**：由 A102 与 VISTA 的硬包络，归因错误只改变软策略与性能，不改变硬安全界；引理 13 保证卡片不把安全动作翻成不安全动作。
2. **基准数字可信**：BVC 有效 ⇒ 引理 14 的误差界在本漂移类内成立，基准分数可当作带界的安全证据；否则 `bench_invalid` 触发降级。
3. **人的决策质量被约束**：UEC 达标 ⇒ 后悔、过/欠信任、时间与负荷都在预算内；引理 15 给出联合安全。
4. **评估失效即降级**：`both_invalid` 时执行 `safe_idle` 并显式拒绝认证，而不是继续自信执行。
5. **证书链**：`Valid(J_lucid)` ⇒ 几何/技能/干扰/接触/归因有效 ∧ 人可决策 ∧ 基准可信 ∧ 评测差距有界 ∧ 评估失效已处理。证书链从「几何-技能-干扰-接触-归因」扩为「…-归因-评估」。∎

**定理 12（评估不可能三角）** 设基准是策略/场景空间到分数的映射 `score_B`，成本为构建与运行该映射的代价。
- 若 `cost(B)=o(|Π|)`，则 `score_B` 必是低维/粗糙摘要，其水平集（等值面）在 Π 中体积不可忽略；
- 对任一高估策略 π（`score_B(π)` 高、`J_deploy(π)` 低），其邻域仍落在同一水平集内（摘要的粗糙性），故存在 π' 同样高分但部署失败 → 不抗 Goodhart；
- 要抗 Goodhart（对所有 π 都 `score_B(π)≈J_deploy(π)`），`score_B` 必须对相关行为近似单射，覆盖数随 Π 的复杂度指数增长，成本不可能 `o(|Π|)`。
故「部署保真 / 低评测成本 / 抗 Goodhart」至多同时满足两项。LUCID 不消除这个三角，而是用 BVC 把当前基准落在三角的哪个位置显式标出。∎

**命题（评测差距是前兆）** 在「置信度先于后果脱节」的常见失效中，`conf_internal` 由模型/证书的自我评估产生，更新快；`Safety` 由真实部署结果产生，更新慢。二者之差 `G⁺` 先增大，随后才出现可观测的安全违规。因此以 `G⁺` 为监控量，可比事后指标提前 τ_lead 触发保守降级。τ_lead 的大小取决于置信估计的更新率与安全后果的延迟，需在 E258 中校准。∎

**命题（评估感知不放大保守性）** 第 65 轮在任意拒绝时统一膨胀 `r=√(r_geo²+r_force²+r_model²)`。LUCID 在评估有效且 `G⁺≤τ_g` 时保持 `r_eval=0`、`r_human` 由 OPM 后验决定；只有在 BVC 失效或 `G⁺>τ_g` 时才膨胀 `r_eval`。若真实故障是几何幻觉而评估器正常，LUCID 的搜索域体积不会因「多了一个评估层」而额外膨胀。∎

## 7. 已知风险

**一句话**：LUCID 的最大风险是**评估的无限回退与「审计剧场」**——可用性证书与基准有效性证书本身也是被测量出来的，而测量它们的人/基准同样会错；一旦 BVC 在「被优化」的基准上自证有效、UEC 在「被挑选」的受试者上自证可用，系统就获得了一张看起来更完备、实则把「谁评估评估者」这一回退藏得更深的证书：**第 65 轮的「错误归因 + 过度自信」由此升级为「错误评估 + 审计合规式自信」**（A101）。

**次级风险与缓解**：
1. **元评估回退（A101）**：BVC/UEC 的可信度无法由自身完全证明。缓解：元评估数据与部署严格分离、时间切分、外部独立审计、把 A101 写入证书的显式假设、在 `both_invalid` 时只用硬包络。
2. **决策卡过度简化**：最简卡可能藏掉低概率但致命的稀有假设。缓解：`δ` 预算显式约束尾部质量；对稀有高危假设强制「分级展开」；E252 专门测长尾。
3. **操作者模型不具普适性**：β_ab、λ_af、T_react 因人和场景而异。缓解：在线个性化 + 保守上界 + 分层/混合效应模型；跨人群验证；反应不达标即自动安全停。
4. **信任校准的伦理风险**：调呈现可能在「操纵」而非「帮助」人。缓解：只允许增加不确定性/证据、不允许隐藏风险；校准目标是最小化决策后悔而非最大化接受率；审计呈现策略。
5. **基准污染检测误报/漏报**：近重复与成员推断都可能有偏。缓解：多种污染指标取最大、留出干净对照、BVC 不确定时默认失效。
6. **MBR 自身过拟合**：红队场景若被用于训练，很快失去证伪力。缓解：红队集与训练集隔离、持续生成新场景、保留 held-out ambush、定期外部 red-team。
7. **评测不可能三角**：无法同时保真、廉价、抗博弈。缓解：显式标注当前基准在三角中的位置；关键安全结论不依赖单一基准；用多基准交叉。
8. **实时预算**：卡片渲染 + 降级触发逼近 2.6ms。缓解：离线预渲染模板、分级加载、把 OPM/CTC/BVC/MBR/EGD 全部留在语义流。
9. **人机责任边界模糊**：证书可能把责任推给人或把人的错误归给机器。缓解：J_lucid 记录「机器给了什么、人看到了什么、人做了什么」的完整审计链，明确每步的认证责任。

## 8. 验收标准（本轮产物自检）

- **概念闭合**：证书是决策接口而非日志；基准是测量仪器而非真值；评估器失效必须显式降级；`G⁺` 是新故障假设。
- **形式闭合**：定义 233–248 与 IP-224–233 一一对应；引理 13–15 覆盖「决策充分 / 基准有效 / 人机安全」三条主链；定理 11–12 给出端到端与评估不可能三角。
- **实验闭合**：E251–E260 覆盖决策卡、决策充分性、信任校准、告警疲劳、基准有效性、红队、基准黑客、评测差距、人机端到端、双重失效。
- **最大风险显式**：A101（元评估回退）已写入证书隐藏假设与红队目标；不靠「再加一张证书」声称解决，而是把「评估器也可能坏」作为一等故障与降级条件。
