# 第 70 轮（承接第 69 轮「FLUID-RAS 交互消歧闭环」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「迭代验证」×「通用操作」）

> R69 把不确定性一分为二，并让系统学会「看、问、触」。但它对**验证本身**的处理仍是一次性的：一个 J_FLUID 闸门、一次性 k-源一致、单位时间至多一次交互。这留下三个从未被追问的问题：**（1）验证能不能分步做，中途被打断还安全吗？（2）验证过的结论能不能存下来、换个任务/换个具身穿还能用吗？（3）谁来保证「验证者」自己不是幻觉、不是被投毒、不是在自证？** R69 自陈的最大风险——模态分布不可信、问错比不问更危险——本质上是**验证的失败**，而单次闸门既无法表达「我到底证到了多少」，也无法在失败时止损。
>
> 本轮两个灵感正好补上：
> - **迭代验证**把「判决」变成「可停止的证据累积」：每步产生可组合证据，随时可停，停下来的前缀仍然是一个合法证书（anytime-valid）；置信是**挣来**的，不是一次宣布的。
> - **通用操作**给出一小组跨任务、跨具身的类型化操作原语（看/动/探/问/等/换/仿真），任何验证都能编译成它们组成的**程序**；于是验证有了中间表示，可以类型检查、可以非扩张认证、可以缓存复用、可以跨具身迁移。
>
> 核心命题：**把验证从「一次性闸门」升级为「基于通用操作基、随时可停、证据可组合、证书可复用」的迭代程序；每个验证操作既花预算又产出证据，证书是程序的前缀，任意时刻中止都保持 R69 的安全下界；R69 恰是「深度 1、单操作、单次」的退化边界。** 命名 **PROVE-RAS**（Program-of-Operations Verification Engine for Risk-adaptive Safety）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「测量准吗」，R69 问「向谁求证、还能问什么」，R70 问「**求证这件事本身能不能被编程、复用、并在任何一刻叫停都仍然安全**」——把验证从一次判决变成一段可执行、可中断、可迁移的程序。

## 0. 直觉与动机

**灵感 1（迭代验证：证据会复利，但复利只在独立通道上成立）**
直觉：人做重要验证从不一次拍板：先看、再问、再试，每一步都可能停，且下一步只在「上一步没解决」时才做。R69 的「k 个正交源一致」其实是一次性问 k 个，既贵又不能中途止损。迭代验证把判决拆成**可停止的证据累积**：达到阈值就接受，出现反证就升级，预算耗尽就回退。难点不在算法，而在**独立性**——把同一个检查重复 100 次不等于验证了 100 次；迭代的证据复利会在相关通道上指数放大幻觉。所以本轮必须同时交付「随时有效」与「独立性核算」两件东西，缺一不可。

**灵感 2（通用操作：验证程序可编译、可迁移、可复用）**
直觉：若验证动作是任务专用的，每换一个场景就要重验一遍，验证成本永远无法摊销。若存在一小组跨任务、跨具身的通用操作，任何任务动作都能编译成它们组成的程序，验证就有了**中间表示**：写一次子程序、验一次、存成带前提的证书，下次只要前提蕴含就可复用。像编译器的 IR：任务千变万化，底层指令集很小；优化的对象从「一个动作」变成「一段程序」。这是把验证从「每次重做」变成「一次编写、到处检查」的关键。

**灵感 3（随时有效：中断即安全，正面回应 R69 的单闸门）**
直觉：R69 的证书是全有或全无——要么过 J_FLUID，要么退回保守。可验证随时会被预算、被人类、被安全事件打断。若证书只能在全程序跑完后才有效，中止就意味着「白做且无保证」。用 e-process / 置信序列构造的 anytime-valid 证书让**每个前缀都是合法证书**：跑到一半停，仍拿到「到目前为止已证到的安全等级」。这不是工程细节，而是把验证从「判决」改成**单调累积的下界**。

**灵感 4（验证摊销与证书传染：通用操作是双刃剑）**
直觉：可复用证书会大幅降低验证成本（一个子程序验一次，N 个任务共享），但也会把一次错误假设传播给 N 个任务：坏证书像流行病一样扩散。R69 的风险是「问错一个幻影」，R70 升级为「把问错的结论盖章复用给一整个场景族」。所以复用必须带**前提条件 + 有效期 + 血缘 + 假设监控**；前提不成立时必须重验，而不是乐观继承。

**灵感 5（谁验证验证者：把信任显式化）**
直觉：验证程序本身也是动作，也可能不安全、被投毒、自证。R69 要求信息动作过 C-RAS-WM 认证；R70 要求验证程序过「验证编译器的类型检查」：每个节点的前提必须由前驱后置条件保证（well-typed），物理足迹必须非扩张，证据必须带依赖签名，递归深度必须有限。验证者被纳入证书，这既新增攻击面，也把「信任」从隐式默认变成显式、可审计的假设。

## 1. 形式化定义（增量：定义 310–326）

**定义 310（通用操作基 UOB）** 𝒪 = (𝒫, τ, Φ, Ψ, π, ι, κ, ρ, β)。原语集 𝒫 = {OBS(ω), ACT(a), PROBE(δ), QUERY(q), WAIT(t), SWAP(σ), SIM(s)}（看/动/探/问/等/换/仿真）。每个 p 有类型签名 τ_p、前条件 φ_p: S→{0,1}、后置条件 ψ_p、物理足迹 π_p（执行后安全裕度的最大减少量）、证据通道 ι_p、成本 κ_p=(t,e,c_social)、风险 ρ_p。**绑定** β: 𝒫→C_emb 把抽象操作落到具体具身指令；β 是唯一与具身相关的部分，其余全部跨具身共享。

**定义 311（操作程序 / 验证程序）** 验证程序 P=(V,E,β,ℓ) 是带类型的有向无环图：v∈V 标一个 p∈𝒫，边表示证据/状态依赖，ℓ 是拓扑序。**良类型**：对每条边 u→v，ψ_u ⇒ φ_v（运行时由假设监控持续检查）。语义 [[P]]: S×Ω→(S',ℰ_P,C_P)。物理足迹 π(P)=Σ_v π_v（保守可加），成本 κ(P)=Σ_v κ_v，证据集 ℰ_P={ι_v}。

**定义 312（证据令牌与独立签名）** 令牌 e=(λ,s,h)：λ 为对数似然比或 e-value，s 为**依赖签名**（来源、模型版本、传感器、时间窗、条件 z），h 为内容哈希。两个令牌**可乘**当且仅当 s 正交（不同物理通道/不同模型/不同时间尺度且条件独立）；否则只能**合并**（e-merge）。

**定义 313（随时有效证书 AVC）** 在验证滤波 (ℱ_t) 上构造非负 e-process E_t（H_bad 下为超鞅，E[E_t]≤1）。证书在水平 α 下随时有效：对任意停时 τ，P_{H_bad}(E_τ ≥ 1/α) ≤ α（Ville 不等式）。停时 τ 可由预算、外部中断、安全事件自适应决定。⇒ **每个前缀都是合法证书**；中止不损失已获证据，也不产生虚假保证。

**定义 314（证据组合与饱和）** 独立**类间**相乘：E_total = Π_cls E_cls；同一依赖**类内**用 e-merge 平均：E_cls=(1/k)Σ_{i∈cls} e_i（任意相关下仍为 e-value）。推论：完全相关的 k 个检查 E_cls=e，增益为 0。故「重复同一检查」只增加成本、不增加置信。

**定义 315（迭代验证控制器 IVC）** 状态 = 当前 e-process + 剩余预算 + 已用依赖类集。每步选
p* = argmax_{p allowed} Δlog E_eff(p) / (κ_p + λ ρ_p)，s.t. 预算与安全；
终止于：(a) E_t ≥ 1/α（接受）；(b) E_t ≤ β_lo 或出现矛盾（拒绝/升级）；(c) 预算/时限耗尽（保守回退）。这是对 R69 单步 VoI 的序贯化。

**定义 316（自适应子模贪心）** 设证据增益 G(A)=E[log E_A] 对操作集 A 自适应子模。贪心每步取最大边际增益/成本，则在基数或成本约束下 G(A_greedy) ≥ (1−1/e)·G(A*)，且与 IVC 停止规则兼容。用于把序贯 POMDP 的精确求解降为可实时执行的贪心。

**定义 317（子程序证书与复用）** 子程序证书 C_P=(φ,ψ,E_bound,β_hash,[t_0,t_1],dep_sig,lineage)。复用条件：φ_new ⇒ φ_old（可证或可监控）、β_hash 一致、在有效期内、dep_sig 未变。复用省 κ(P)，但要付前提检查 κ_check 与漂移风险 P_drift·L_drift。

**定义 318（证书传染与隔离）** 若 C_P 的某前提在复用时为假，则其后代证书全部被污染。污染集 Contam(C_P)={C_Q : C_P∈lineage(Q)}。检测到前提失效即隔离 Contam 并强制重验，禁止乐观继承。若单证书失效率 δ_c、血缘深度 ℓ、复用广度 b，未隔离时污染规模可达 b^ℓ，隔离后 ≤ δ_c·b。

**定义 319（验证深度与信任基）** 检查前提本身也要验证，可能无限回归。定义验证深度 d：d=0 为**信任基** 𝒯（硬件互锁、已认证传感器、签名绑定），d>0 的前提检查必须由深度 ≤ d−1 的程序完成。总验证成本 ≤ C_0·b^d；d 有限即成本有限。信任基 𝒯 是显式、可审计的假设，而非隐式盲信。

**定义 320（跨具身绑定细化）** 绑定 β 是**细化**，若对每个 p：β 的具体指令在前条件上等价、在后置条件上更强、在足迹上不超过 π_p。细化保持证书有效性，但引入绑定误差 ε_bind（标定/运动学残差）。跨具身迁移的总误差 ≤ ε_bind + sup_t drift(t)。

**定义 321（操作级非扩张性）** p 是 ε_p-非扩张的，若执行 p 后状态到安全边界的裕度减少 ≤ ε_p。验证操作优先选 ε_p=0（OBS/WAIT/SIM）；PROBE/ACT/SWAP 需 ε_p ≤ ε_g 且过 C-RAS-WM 前缀认证。复合 P 的非扩张常数 ≤ Σ_v ε_v。

**定义 322（验证程序审计 VQAuditor-P）** 审计对象从「交互决策」升级为「验证程序」：证据是否被错计为独立、复用前提是否真的检查过、深度是否越界、绑定是否细化、假设监控是否在线、是否把 SIM 证据当物理证据。结论回灌 AuditBuf，成为下一轮 IVC 的成本/独立性先验。

**定义 323（通用操作攻击面 ℰ_PROVE）** ℰ_PROVE = ℰ_FLUID × ℰ_replay（重放旧证书）× ℰ_compose（前提洗白/坏组合）× ℰ_confirm（自证/相关证据）× ℰ_bind（跨具身绑定错配）× ℰ_sim（仿真证据伪造）。并入 AIC-PROVE。

**定义 324（证书 J_PROVE）** J_PROVE=(J_FLUID, program_hash, e_trace, τ_stop, indep_sig, depth d, reuse_lineage, β_hash, assumption_monitors)。Valid ⇔ Valid(J_FLUID) ∧ E_τ ≥ 1/α ∧ 独立性纪律 ∧ d ≤ d_max ∧ 复用前提已检查 ∧ 假设监控在线。

**定义 325（PROVE-RAS 总览与四不变式）** PROVE-RAS=(UOB, VPC, AVC, IVC, CRA, RAS-WM‡)。不变式：(i) 实时流零学习写（继承 R68/R69）；(ii) **验证者自证**：每个验证操作本身过 C-RAS-WM 认证且非扩张；(iii) **随时可停**：任意前缀是合法证书，中止即回退 R69 保守下界；(iv) **独立性核算**：相关证据增益饱和，不得用重复检查伪造置信。

**定义 326（R69 退化边界）** 当 |V|=1（单操作）、无复用、证据全部独立、只跑一步时，IVC 退化为 R69 的单步 VoI 与 J_FLUID 闸门；PROVE-RAS 与 FLUID-RAS 逐指令相同。R69 是本方案在「深度 1 / 单操作 / 单次」边界上的严格退化。

## 2. 关键算法骨架

```python
# IP-264 UOB：通用操作基与具身绑定（唯一具身相关部分）
class UniversalOps:
    OPS = {OBS, ACT, PROBE, QUERY, WAIT, SWAP, SIM}
    def bind(self, p, emb): ...        # 抽象操作 -> 具身指令（refinement）
    def footprint(self, p, s): ...     # 物理足迹 pi_p
    def evidence(self, p, y): ...      # -> (e-value, dep_sig, hash)

# IP-265 VPC：验证程序编译器（类型/非扩张/深度三重检查）
def compile_program(goal, ops, trust_base, d_max):
    P = synthesize_dag(goal, ops)              # 目标 -> 操作 DAG
    assert well_typed(P)                       # 每条边 psi_u => phi_v
    assert footprint(P) <= EPS_G               # 物理足迹不越界
    assert depth(P) <= d_max                   # 验证深度有界
    return P

# IP-266/268 IVC+EDA：迭代验证（随时可停 + 相关证据饱和）
def iterate_verify(P, H, alpha, beta_lo, budget):
    E, used = 1.0, set()
    while budget.remaining():
        cand = [p for p in P.ready()
                if budget.allow(p) and c_ras_wm.certify(p)
                and indep_ok(p, used)]
        if not cand: break
        p = argmax(cand, key=lambda p: gain(p, H) / cost(p))
        e = ops.evidence(p, execute(p))        # e-value + dep_sig
        if e.sig not in used: E *= e.value     # 类间乘
        else: E = merge_within(e.sig, e)       # 类内平均 -> 饱和
        used.add(e.sig)
        if E >= 1/alpha: return ACCEPT, E, used
        if E <= beta_lo: return REJECT, E, used
    return FALLBACK_R69, E, used               # 任意前缀仍是合法证书

# IP-269/270 CRC：复用、传染隔离、前提监控
def replace_reusable(C, new_pre, now, beta_hash):
    if not implies_or_monitored(new_pre, C.pre): return None
    if C.beta_hash != beta_hash or now > C.t1:   return None
    if C.dep_sig.changed():                      return None
    return C if budget.cost(C.kappa_check) < budget.cost(C.kappa_reverify) else None

def on_precondition_violation(C):
    quarantine(Contam(C))                        # 隔离全部后代，强制重验

# IP-274 主闭环（继承 R69，把单闸门换成可中断程序）
def PROVE_RAS_round(M, obs):
    z, o = M.mtm.forward(...); c, U_cal, thr = M.cof.step(...)
    K = 1 if M.fmp.mode_head(z) < TAU_MODE else 4
    U_ale, U_epi, modes, _ = M.aud.decompose(M.fmp.sample(o, K), z, M.fmp.mode_head)
    a_hat = M.fma.flow_anomaly(M.fmp, M.last_action, o_obs, o_cal)
    # 把「该信哪个证书/假设」编译成验证程序，并优先复用
    goal = certify_goal(U_epi, a_hat, M.last_r_res)
    P = M.vpc.compile(goal, M.uob, M.trust_base, d_max=3)
    P = M.cache.replace_reusable(P, o, M.uob.bind(M.emb)) or P
    verdict, E_t, used = M.ivc.iterate(P, goal.H, M.alpha, M.budget)
    if verdict is REJECT: M.escalate()            # 交人 / 请求示范
    lam = max(M.efs.risk_scale(...),
              lam_floor(U_ale + (U_epi if verdict is not ACCEPT else 0.0)))
    k = M.c_ras_wm.certified_prefix(...)          # 非扩张前缀
    M.auditor_p.submit_async(P, E_t, used, verdict)
    return k, lam, verdict, J_PROVE(...)
```

## 3. 推导

**引理 19（随时可停的合法性）** 设 E_t 为 H_bad 下的非负超鞅（E[E_t]≤1）。对任意停时 τ（可依赖预算、中断、安全事件），Ville 不等式给出 P_{H_bad}(E_τ ≥ 1/α) ≤ α。故在任意前缀停止都保持水平 α，停止规则不影响证书有效性。对比固定样本检验：边看边停会抬高第一类错误；e-process 的超鞅性质正是为「边验边停」而生。

**引理 20（相关证据的增益饱和）** 同一依赖类内 k 个检查经 e-merge 后为 E_cls=(1/k)Σ e_i。若完全相关（e_i≡e）则 E_cls=e，增益为 0；一般情况下 log E_total = Σ_cls log E_cls ≤ m·log e_max，其中 m 为独立依赖类数。即：**置信增长上界由独立通道数 m 决定，与总执行次数 k 无关**。系：IVC 的 indep_ok 约束不是保守装饰，而是使迭代验证不退化为自证的必要条件。

**引理 21（验证摊销）** 无复用 N 个任务的验证成本为 N·κ(P)；有复用且前提检查成本 κ_c，则成本为 κ(P)+N·κ_c，加速比 s=Nκ(P)/(κ(P)+Nκ_c)→κ(P)/κ_c。当且仅当 κ_c + P_drift·L_drift < κ(P) 时复用划算。这是「通用操作」的红利：把一次性验证变成可摊销资产。

**定理 18（PROVE 严格包含 FLUID-RAS）** 在定义 326 的边界（|V|=1、无复用、证据独立、单步），PROVE-RAS 与 FLUID-RAS 逐指令相同。一般情形下，因所有验证操作非扩张（定义 321）、任意中止回退 R69 保守下界（定义 325-iii），PROVE 在任意状态 s 的期望风险 ≤ FLUID；效率侧由多步序贯与复用获得增益。故 R69 是「深度 1 / 单操作 / 单次」边界上的退化，安全侧不做任何让步。

**定理 19（有界终止与实时预算）** 在 H_alt 下每步的 KL 证据增量为 D，则到达 1/α 的期望步数 ≤ log(1/α)/D（Wald）；最坏步数由预算硬截断。程序 DAG 节点数 ≤ n_max、深度 ≤ d ⇒ 运行时 ≤ Σ_v κ_v ≤ B。故迭代验证不会发散，且 optional stopping 不引入偏差（超鞅性）。

**定理 20（跨任务/跨具身迁移的可靠性）** 若绑定 β 为细化（定义 320）且假设监控在线，则迁移证书的误差 ≤ ε_bind + sup_t drift(t)。当漂移超过阈值时缓存自动失效并触发重验（定义 318 隔离），因此迁移路径在安全侧不弱于重验；效率侧由引理 21 的摊销给出。

**定理 21（验证非扩张保持无突变）** ε-非扩张操作的复合仍为 (Σε)-非扩张；验证程序的前缀始终落在已认证安全包络内，控制连续、无突变。这继承并推广 R69 定理 17：不仅交互不改变安全包络，**验证本身也不改变安全包络**。

```python
                and c_ras_wm.certify(p) and indep_ok(p, used)]
        if not cand: break

        e = ops.evidence(p, execute(p))

        used.add(e.sig)

        if E <= beta_lo: return REJECT, E, used

         and now <= C.t1 and not C.dep_sig.changed()
```

## 4. 推导

**引理 19（随时可停合法性）** E_t 为 H_bad 下非负超鞅，对任意停时 τ 有 P(E_τ≥1/α)≤α（Ville）。⇒ 任意前缀即证书，中止安全；固定样本「边看边停」会抬高第一类错误，本方案不会。

**引理 20（相关证据饱和）** 类内 e-merge：完全相关 k 次增益 0；一般有 logE_total = Σ_cls logE_cls ≤ m·log e_max，m 为独立类数。⇒ 置信上界由独立通道数决定，与执行次数无关；indep_ok 是必要约束。

**引理 21（验证摊销）** 有复用成本 κ(P)+Nκ_c，加速比 →κ(P)/κ_c；当 κ_c+P_drift·L_drift<κ(P) 时复用划算。

**定理 18（严格包含 R69）** 单操作/单步/无复用/独立证据时逐指令相同；一般情形因非扩张 + 任意中止回退，期望风险 ≤ R69；效率由多步与复用获得。R69 = 深度 1 边界退化。

**定理 19（有界终止）** H_alt 下每步 KL 增益 D，则期望步数 ≤ log(1/α)/D；最坏由预算截断；DAG ≤ n_max、深度 ≤ d ⇒ 运行 ≤ Σκ_v ≤ B。无发散，optional stopping 无偏。

**定理 20（迁移可靠性）** 绑定细化 + 监控在线 ⇒ 误差 ≤ ε_bind + sup drift；超阈值即隔离重验，安全侧不弱于重验。

**定理 21（非扩张无突变）** Σε-非扩张复合保持安全包络；验证前缀始终在认证包络内，控制连续无突变（推广 R69 定理 17）。
