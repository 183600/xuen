# 第 43 轮（新循环第 3 轮） · Step-Score × ROS 2：把「可进化证书飞轮」落成「可自证伪、可热更新、可审计」的步骤分运行时（四层架构 v8）

> 承接第 42 轮 v19（Sim-Cert-RAG 飞轮）。第 42 轮自陈最大风险是「仿真偏差累积 + 检索幻觉」造成的**静默失效**：证书在自信中慢慢失真，比显式降级更危险。本轮灵感词「步骤分」「机器人操作系统」正好给出两把手术刀：**步骤分**把证书从「一次性/二值守卫」变成「每控制步可度量、可分解、可追溯的稠密信用」，于是预测分与实测分的**跨路径差值**本身就是一个在线自证伪信号；**ROS 2** 把飞轮从论文架构落到真实节点图，用 Lifecycle 做证书蓝绿热更新、用 QoS（deadline/liveliness/durability）把 T_hold 变成可执行的时间契约、用 rosbag2 做不可篡改的步骤分账本与重放回归。二者合起来，让第 42 轮「不可观测的静默失效」变成「每一步都可被对账的显式事件」。

## 0. 直觉与动机

**灵感 1（步骤分 → 证书的「过程奖励」与「对账凭证」）**：第 42 轮的证书仍是「终点/守卫式」的：只有在跨边时才检查 m_lo ≥ θ，中间步的安全余量、信息充分性、任务进展都被压成一个瞬时阈值。借鉴 RL 里 process reward model（PRM）的思想，**步骤分**的直觉是：不要只在终点打分，而是给每个控制步一个稠密分数 S_t=(s_safe, s_util, s_info, s_future)，并把「未来最坏步骤分」做成一个保守的值函数 V_C(x)（离散 HJ 值迭代），离线存进 L0 表、在线只查表。更重要的是——**步骤分是一条可以「对账」的账**：运行时用 L0/L1 产生预测分 ŝ_t，审计路径（独立仿真重放/物理残差/区间电路）产生实测分 s_t^real；两者若长期一致，证书可信；若出现系统性乐观差（ŝ_t > s_t^real + ε），就说明证书正在「说谎」。这把第 42 轮最怕的静默失效，转成一个**可检验的假设**，而不是一个无法观测的隐患。

**灵感 2（ROS 2 → 证书的「骨骼」与「时间契约」）**：第 41/42 轮的总线 IP-45 一直停留在抽象「话题」。ROS 2 的直觉是把它落地为一组有生命周期的节点：`cert_monitor`（LifecycleNode）负责 L0/L1 步骤分；`cert_supervisor` 负责守卫与降级；`cert_auditor` 负责跨路径对账；`cert_registry` 负责证书版本。关键有三点：**QoS-as-Contract**——把 T_hold 直接实现为 step-score 话题的 DEADLINE 周期与 monitor 的 LIVELINESS 租约，deadline/liveliness 违约不是告警而是**证书失效**；**Lifecycle 蓝绿热更新**——新证书先 `configure` 校验、再 `inactive` 影子运行、最后原子 `activate`，任何不一致自动 `rollback`，保证任意时刻至少一份 sound 证书在岗；**rosbag2 账本**——每步记录 (状态, 动作, 步骤分, 证书哈希, 随机种子, 监控版本) 并用哈希链串接，`ros2 bag play` 可确定性重放，新证书可在历史轨迹上做「证书差分回归」，把检索幻觉/仿真偏差在部署前就抓出来。

**耦合升级**：步骤分是流经 ROS 2 节点图的「通货」，ROS 2 是承载步骤分与飞轮的「骨架」。原来的 Sim→RAG→Edge→Sim 飞轮，现在多了一条 **Edge→Audit→Sim** 的「自证伪」回路：审计分差触发 e-process 漂移检验（任意时刻有效，Ville 界控假警），确认后回灌 Sim 与 KB。证书不再只是「被验证」，而是「持续地在验证自己」。

## 1. 形式化定义（增量：定义 38–43）

**定义 38（步骤分证书 / Step-Score Certificate）**：给定证书 C=(G, Inv, θ, L_m, T_hold) 与控制步 t 的状态-动作 (x_t,u_t)，定义四通道步骤分
s_t = (s^safe_t, s^util_t, s^info_t, s^fut_t)，
其中 s^safe_t = clip((m_lo(x_t,u_t)−θ)/(m_ref−θ),0,1) 为归一化安全余量；s^util_t = clip(ΔΦ_t/ΔΦ_ref,0,1) 为任务势能进展；s^info_t = 1−U_t/U_max 为信息充分性（漂移/可观测/语义歧义）；s^fut_t = min_{τ∈[t,t+H]} s^safe_τ 为 H 步前瞻安全下界。**标量步骤分** σ_t = min(s^safe_t, s^fut_t, g(s^util_t,s^info_t))，取 min（安全 t-范数）保证保守性。**命题（步骤分下界性）**：若各通道均为对应真实量的下界，则 σ_t ≤ 真实归一化安全余量，且 min 运算与单调降级相容，故 σ_t 可直接作为 sound 的运行时守卫信号。

**定义 39（步骤分值函数与保守组合）**：定义证书值函数 V_C(x_t) = min_{u_{t:t+H}} min_{τ∈[t,t+H]} σ_τ，满足无折扣递推 V_t = min(σ_t, V_{t+1})，V_{t+H+1}=1（安全不可折扣，故不用 γ）。离线用离散 HJ/可达性值迭代求出网格值并入 L0 表；在线 V_C 只做 O(log N) 查表 + 插值。**性质**：V_C(x) 是「未来 H 步最坏步骤分」的 sound 下界；组合技能时 V_{C1⊗C2} = min(V_{C1}, V_{C2})，与 IP-47 乘积代数天然一致。

**定义 40（跨路径步骤分对账 / Cross-Path Step-Score Auditing, CPSA）**：设运行时监控给出预测分 ŝ_t，独立审计路径给出实测分 s^real_t（审计路径必须在方法上独立：不同仿真种子/不同数值格式/不同证书档，避免共模失效）。定义**乐观差** d_t = ŝ_t − s^real_t，与**对账完整性条件** sup_{t∈W} d_t ≤ ε_score（W 为滑窗）。若违反，则证书进入 `Suspect` 状态，触发降级 + 飞轮审计。**定理（静默失效可检出性）**：若真实乐观偏差 ≥ ε_score+δ 且审计路径与监控路径不共模，则 CPSA 在期望 O(1/δ²) 步内以高概率检出；反之若两路径共模，则检测退化为 0——这就是本轮把「审计路径独立性」列为红线的原因。

**定义 41（QoS-证书时间契约）**：把 ROS 2 QoS 映射为证书的时间语义：step-score 话题 `DEADLINE=T_step`、monitor `LIVELINESS=AUTOMATIC(lease=T_hold)`、证书更新 `DURABILITY=TRANSIENT_LOCAL`、安全守卫 `RELIABILITY=RELIABLE`、步骤分窗口 `HISTORY=KEEP_LAST(depth=W)`。定义证书在 t 时刻**时间有效**当且仅当：最近一次有效步骤分年龄 a_t ≤ T_hold，且无 deadline/liveliness 违约。违约直接令 σ_t←0（保单边），从而把「通信/调度故障」纳入证书失效域，而非当作普通告警。

**定义 42（Lifecycle 蓝绿证书热更新）**：证书状态机 `unconfigured→inactive→active→retired`。新证书 C_new 先在 `inactive` 影子模式运行 k 步，比较其步骤分与在岗证书 C_old 的决策差 δ_swap = max_t |σ_new,t−σ_old,t|；仅当 δ_swap ≤ ε_swap 且两证书在切换点状态上均 sound 时，才原子 `activate`。**切换不变式**：任意时刻存在唯一 active 证书，且切换区间内 C_old 与 C_new 的守卫交集仍成立（单调保守交接），否则自动 `rollback` 到 C_old。**命题**：在交接不变式下，热更新不引入新的不安全状态。

**定义 43（步骤分 e-process 漂移检验）**：以乐观差 d_t 构造检验鞅。对 H0「监控无系统性乐观」取 e_t = exp(λ d_t − λ²c²/2)（d_t 次高斯，|d_t|≤c），E_t = ∏_{i≤t} e_i 为非负鞅，由 Ville 不等式 P(sup_t E_t ≥ 1/α) ≤ α，故任意时刻拒绝 H0 的误报率 ≤ α。拒绝即触发飞轮（Sim 重采样 + KB 审计 + 证书重颁）。**性质**：相比第 42 轮启发式 W_1 阈值，e-process 给出**随时有效（anytime-valid）**的假警控制，并把期望检测延迟由 KL(d||0) 界住。

## 2. 四大产出设计（增量 IP-57/58/59 + 升级既有）

### 2.1 IP-57 STEP-SCORE-ENGINE（SSE，步骤分引擎）
1. **四通道打分**：安全/进展/信息/前瞻；安全通道复用 IP-49 几何证书与 L0 表，进展通道用任务势能（导航距离、抓取可达性），信息通道用协方差迹 + 语义熵，前瞻通道用离散 HJ 值迭代缓存。
2. **值函数压缩**：离线值迭代 → 八叉树/克拉普顿树 → L0 只读表；在线 O(log N) 查表 + 保守插值（下取整，保 sound）。
3. **对账接口**：输出 (ŝ_t, 各通道, 证书哈希, 见证 witness)；见证 = 触发下界的约束/采样点，供审计路径独立复算。
4. **信用分配**：审计失败时用反事实重打分（替换 Sim 种子/证书模板/量化精度）估计各来源的 Shapley 近似贡献，输出 blame 向量。

### 2.2 IP-58 ROS2-CERT-RUNTIME（RCR，证书运行时节点图）
1. **Lifecycle 节点族**：`cert_monitor`、`cert_supervisor`、`cert_auditor`、`cert_registry`，全用 managed lifecycle，支持 `configure/activate/deactivate/cleanup` 与故障隔离。
2. **QoS 契约层**：按定义 41 设定 deadline/liveliness/durability/reliability；deadline 违约回调直接把步骤分置零并切 SafeStop。
3. **蓝绿热更新**：`cert_registry` 下发候选证书 → `cert_monitor` inactive 影子运行 → `cert_supervisor` 比对 δ_swap → 原子激活/回滚。
4. **零拷贝与实时**：Intra-process composition（loan message）+ 高优先级 callback group + 静态 executor，把 L0 查表与 INT8 监控放进同一进程，目标端到端 < 200μs。
5. **生态插件**：Nav2 controller/planner 插件、MoveIt 规划场景插件、ros2_control 控制器切换守卫；micro-ROS 覆盖 STM32H7 级 MCU。

### 2.3 IP-59 CERT-AUDIT-LEDGER（CAL，证书审计账本）
1. **步骤分账本**：rosbag2 记录每步 (x,u,σ,通道分,证书哈希,种子,监控版本,QoS 事件)，用 Merkle 哈希链防篡改。
2. **确定性重放**：固定种子 + 固定时钟源 + 版本锁，`ros2 bag play` 可重放；审计路径用独立仿真/独立数值格式复算 s^real。
3. **证书差分回归**：新证书在历史账本上重放，标出 σ_new 与 σ_old 分歧步；分歧必须被差集 Δ 覆盖或人工确认，否则阻止上线。
4. **取证与归因**：失败轨迹 → 逐步反事实 → blame 向量 → 写入 CKB（IP-55）Ξ 集，形成「事故→模板修正」闭环。

## 3. 四层架构 v8（ROS 2 节点图）

```
L1  [ros2_control / sensor drivers] → TRI-FUSE(INT8, Q15.16) + IP-49 LIO
     → /cert/state (RELIABLE, DEADLINE=T_step) → C_ms, B_t, L_m
L2  CTC/VLM/仲裁 → R_φ(w) + 几何残差证书 → /cert/fingerprint (φ,ψ,QoS profile)
L3  cert_monitor(Lifecycle, composition) ── /cert/step_score (DEADLINE, KEEP_LAST W)
      ├─ L0 查表 V_C/σ (5μs) ── L1 INT8 四通道 (100μs) ── L2 定点 TRI-FUSE
      └─ cert_supervisor ← 守卫/降级/SafeStop；Nav2/MoveIt 插件消费 σ
    cert_registry ── /cert/swap (action, TRANSIENT_LOCAL) ── 蓝绿热更新
    cert_auditor ── 独立仿真/区间复算 s_real ── /cert/audit (e-process)
L4  IP-54 SCV → IP-55 CKB(RAG) → IP-50 课程 → IP-44 蒸馏 → IP-57 SSE 值函数
    → RCA 重颁证书(版本+有效域) → /cert/swap；失败账本回灌 SCV/CKB
    运行期：账本 rosbag2(Merkle) → 重放差分回归 → 审计分差 → e-process → 飞轮
```

## 4. 实验设计（E87–E94 硬门槛，承接 E79–E86）

| 实验 | 指标 | 门槛 |
|---|---|---|
| E87 步骤分下界性 | 实测归一化余量 ≥ σ_t 的比例；插值违例 | ≥99.9%；0 起越界 |
| E88 跨路径对账检出 | 注入仿真偏差/INT8 乐观/模板毒化后的检出率、误报、延迟 | ≥95%；≤1 次/天；≤20 步 |
| E89 QoS 时间契约 | deadline/liveliness 注入下的 fail-safe 比例；静默死亡 | 100% 在 T_hold 内降级；0 例静默 |
| E90 Lifecycle 热更新 | 1000 次随机切换的不安全区间；回滚时延 | 0 起；<50ms；影子分歧可检出 |
| E91 账本重放回归 | 重放确定性；植入回归检出率；篡改检出 | bit-exact；≥98%；100% |
| E92 e-process 漂移 | H0 下 10^6 步误报率；检测延迟 vs KL 界 | ≤α；≤1.5x 理论界 |
| E93 步骤分信用分配 | 注入故障的 blame 定位准确率；人工审计时间 | ≥90%；<3min |
| E94 端到端 ROS 2 部署 | Orin Nano/micro-ROS 端到端延迟；24h 稳定性 | 附加开销 <200μs；0 不安全 |

回退：E87 下界被破 → 关闭步骤分只保 L0 margin + SafeStop；E88 对账无独立增益 → 改纯重放审计；E89 QoS 违约抖动 → 放宽 deadline 并显式建 Degraded；E90 切换不安全 → 冻结证书版本、停机窗口人工切换；E91 重放不确定 → 固定容器镜像与随机源；E92 误报超界 → 降 α/加 EWMA 但要重标定。

## 5. 本轮最大风险

**一句话**：步骤分把证书变成「可对账」的同时也引入了**审计共模失效**——若审计路径与运行时监控共享同一仿真、同一量化模型或同一传感器假设，两者会同错而「对账通过」，静默失效反而被包装成高置信；因此 E88（多样化注入）与 E91（独立重放）必须作为红线，且审计路径必须强制异构（不同种子/数值格式/证书档）。

| 符号 | 含义 | 定义 |
|---|---|---|
| s_t=(s^safe,s^util,s^info,s^fut) | 四通道步骤分 | 安全余量/任务进展/信息充分性/H步前瞻下界，各 ∈[0,1] |
| σ_t=min(s^safe,s^fut,g(s^util,s^info)) | 标量步骤分 | 安全 t-范数合取，保守下界 |
| V_C(x)=min_{τ≤H}σ_τ | 步骤分值函数 | 无折扣递推 V_t=min(σ_t,V_{t+1})，离散 HJ |
| ŝ_t / s^real_t | 预测分/实测分 | 运行时监控 vs 独立审计路径 |
| d_t=ŝ_t−s^real_t | 乐观差 | >0 表示监控偏乐观（危险方向） |
| ε_score, W | 对账阈值/滑窗 | 完整性条件 sup_W d_t ≤ ε_score |
| E_t=∏exp(λd_i−λ²c²/2) | 步骤分 e-process | 非负鞅；Ville 界控 anytime 误报 ≤α |
| QoS=⟨deadline,liveliness,durability,reliability,history⟩ | 时间契约 | T_hold=deadline/liveliness 租约；违约⇒σ=0 |
| δ_swap, ε_swap | 蓝绿分歧/阈值 | 影子步 δ_swap=max|σ_new−σ_old|；≤ε_swap 才切换 |

## 2. 关键算法（伪代码）

### IP-57 SSE：步骤分、值函数与对账
```
def step_score(x, u, cert, L0, horizon=H):
    s_safe = clip((L0.margin_lo(x,u) - cert.theta) / (cert.m_ref - cert.theta), 0, 1)
    s_util = clip(delta_potential(x,u,goal) / POT_REF, 0, 1)
    s_info = clip(1 - (trace(P) / P_MAX + semantic_entropy(x)/H_REF)/2, 0, 1)
    s_fut  = L0.value_lookup(x)              # = min_{τ<=H} s_safe, sound lower bound
    sigma  = min(s_safe, s_fut, g(s_util, s_info))
    witness = L0.witness(x)                  # 触发下界的约束/采样点，供审计独立复算
    return StepScore(s_safe, s_util, s_info, s_fut, sigma, witness, cert.hash)

def offline_value_iteration(cert, grid, H):
    # 离散 HJ：V(x)=min(s_safe, min_{u} V(f(x,u)))，H 步截断，取保守下界
    V = {x: 1.0 for x in grid}
    for _ in range(H):
        V = {x: min(safe_lower(x), min(V[nxt(x,u)] for u in U(x))) for x in grid}
        V = conservative_round_down(V, eps_grid)   # 关键：向下取整保 sound
    return build_kd_tree(V)

def cross_path_audit(monitor, auditor, window):
    for t in window:
        shat = monitor.predicted_score(t)      # L0/L1
        sreal = auditor.independent_score(t)   # 独立仿真/区间/异构数值
        d = shat - sreal
        E = eprocess_update(E, d)              # 见 IP-56 drift
        if d > EPS_SCORE or E >= 1/ALPHA:
            return Verdict.SUSPECT, blame(monitor, auditor, t)
    return Verdict.OK

def blame(monitor, auditor, t):
    # 反事实重打分：替换 Sim 种子/证书模板/量化精度，估 Shapley 近似贡献
    base = auditor.independent_score(t)
    contrib = {}
    for src in ['sim_seed', 'template', 'quant', 'qos']:
        perturbed = auditor.score_with(source=src, variant='alt')
        contrib[src] = abs(base - perturbed)
    return normalize(contrib)
```

### IP-58 RCR：Lifecycle 蓝绿热更新 + QoS 契约
```
class CertMonitor(LifecycleNode):
    def on_configure(self, state):
        self.L0 = load_mmap(self.params.cert_table)
        self.L1 = load_int8(self.params.model)         # 见 IP-56
        return TransitionCallbackReturn.SUCCESS
    def on_activate(self, state):
        self.step_pub = self.create_publisher(StepScore, '/cert/step_score',
            QoSProfile(reliability=RELIABLE, deadline=Duration(T_STEP),
                       liveliness=AUTOMATIC, liveliness_lease=Duration(T_HOLD),
                       durability=TRANSIENT_LOCAL, history=KEEP_LAST(W)))
        self.create_timer(T_STEP, self.tick, callback_group=RT_GROUP)
        return super().on_activate(state)
    def tick(self):
        ss = step_score(self.state, self.action, self.cert, self.L0)
        if self.deadline_missed_recently or self.liveliness_lost:
            ss = ss.zeroed()                            # 时间契约违约 ⇒ 保单边
        self.step_pub.publish(ss)

def blue_green_swap(registry, old_cert, new_cert, k=100):
    new_node = registry.spawn_inactive(new_cert)        # configure + 校验
    div = 0.0
    for _ in range(k):                                  # 影子运行
        old_ss = registry.old_monitor.peek_score()
        new_ss = new_node.peek_score()
        div = max(div, abs(new_ss.sigma - old_ss.sigma))
    if div > EPS_SWAP or not overlap_sound(old_cert, new_cert):
        registry.retire(new_node); return 'ROLLBACK'
    # 交接不变式：两证书守卫交集成立的瞬间原子切换
    registry.atomic_activate(new_node, guard=guard_intersection(old_cert,new_cert))
    return 'ACTIVE'
```

### IP-56 升级：L0 值函数表 + e-process 漂移
```
def cert_lookup_L0_v2(x_quant):
    key = pack_key(x_quant)
    node = kd_tree_traverse(root, key)
    val = trilinear_round_down(node, x_quant.frac)      # 向下取整，保 sound
    return unpack(val)   # V_C, sigma_channels[4], witness, theta_vec, j_star

def eprocess_update(E, d, lam=LAMBDA, c=C_SUBGAUSS):
    return E * exp(lam*d - lam*lam*c*c/2)               # H0 下非负鞅

def drift_gate(E, alpha=ALPHA):
    return E >= 1.0/alpha                               # Ville: P(sup E>=1/α)<=α
```

## 5. 风险与缓解（增量）

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 审计共模失效：监控与审计共享仿真/模型 ⇒ 同错而「对账通过」 | 高 | 强制异构审计路径（不同种子/数值格式/证书档）；E88 多样注入；E91 独立重放 |
| 步骤分被「刷分」：优化 σ 而非真实安全（Goodhart） | 高 | σ 只由可验证下界通道构成；进展/信息通道不得进入安全合取；E87 下界性红线 |
| 值函数离散化过保守导致可用性下降 | 中 | 网格自适应加密 + 分层存储；向下取整仅用于安全通道；Degraded 档位缓冲 |
| QoS deadline 过紧引发频繁误降级 | 中 | deadline 标定用 p99 调度延迟；违约需连续 k 次才降级；EWMA 平滑 |
| 蓝绿影子运行与实机分布不一致 | 中 | 影子跑真实在线分布；切换前做历史账本差分；ε_swap 按证书风险分级 |
| rosbag 账本膨胀与写入抖动 | 中 | 分片 + 压缩 + 异步写；关键步全量、非关键步摘要 |
| e-process 检测延迟过长（小偏差） | 低-中 | 自适应 λ / mixture e-process；与 W_1 粗检并行双保险 |

## 6. 本轮最大风险

**一句话**：步骤分把证书变成「可对账」的同时也引入了**审计共模失效**——若审计路径与运行时监控共享同一仿真、同一量化模型或同一传感器假设，两者会同错而「对账通过」，静默失效反而被包装成高置信；因此 E88（多样化注入）与 E91（独立重放）必须作为红线，且审计路径必须强制异构（不同种子/数值格式/证书档）。
