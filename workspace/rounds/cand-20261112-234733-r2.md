# 第 3 轮迭代 · 灵感循环 v3 第 1 轮（「腕部相机」×「强化学习」）—— 用腕部自运动残差，把“成功演示”改写成“恢复训练集”

> **承接 v2（UIP-01′~15：Gazebo 计分神谕 × 实时性 × 模块化）**。v2 把最大得分缺口锁定为“人为反向撤回”，但留了两个没解的问题：**(a) 撤回检测器没有撤回样本，怎么学？(b) 恢复策略没有恢复数据，怎么训？** 本轮用两个灵感词的交叉回答：**腕部相机让“撤回”退化成可解析的几何残差（不需要撤回样本）；强化学习让“成功演示”通过事后目标重标注变成恢复题（不需要恢复数据）**。同时按官方 README 硬修正 v2 的一条接口错误：`action_chunk_size` 是握手时固定的全局常数，v2 的 ACS“运行期变块长”不成立。

## 0. 先给三个直觉画面（不严谨，先抓住）

1. **腕部相机 = 装在手上的显微镜 + 免费的陀螺仪。** 它离物体只有十几厘米，能看到插头倒角、拉链齿、毛巾褶；更重要的是它与手**刚性连接**——手怎么动，相机就怎么动。于是“画面里有没有东西不跟着我的手动”就是一个**不需要训练**的异常信号：抓着的东西滑了、被人拿走了、被人拧回去了，都会在腕部画面里留下“违反应当刚体运动”的残差。
2. **机器人自己的位姿是白送的。** 接口直接给 `left/right_ee_pose_gripper_base[6]`（基座系 `xyz+rpy`），腕部彩色相机的内参也在数据集元信息里。我们不需要估计“机器人在哪”，只需要解释“**物体相对我的手发生了什么**”。这把问题从“重识别整张图”压缩成“解释腕部画面相对手运动的偏差”。
3. **RL 不是在线试错，而是把成功演示重新切分。** 公开数据没有恢复样本，但每条成功演示里都藏着恢复题：毛巾第 100 帧叠好，第 60 帧就是它的“未叠好”状态；第 60 帧 → 第 100 帧这段，本来就是“从退回状态恢复到目标”的轨迹。**成功演示的时间轴，本身就是一部反向的失败史。** 事后目标重标注（hindsight relabeling）把这部分免费数据挖出来；仿真再补上“人把物体拿到演示分布之外”的那部分。

## 1. 再给严谨定义（把直觉钉死）

### 1.1 已知量与记号

记基座系 `b`、末端系 `e`、腕部相机系 `c`、物体系 `o`。接口已给：

- 末端位姿 `T_{e←b}(t)`：来自 `left/right_ee_pose_gripper_base[6]`（`xyz+rpy`，需转成 `SE(3)`）；
- 腕部彩色内参：左 `f_x≈436.4, f_y≈435.9, c_x≈323.9, c_y≈242.9`；右 `f_x≈435.1, f_y≈434.5, c_x≈319.0, c_y≈241.0`（`camera_params`，`inverse_brown_conrady`）；
- 关节角与夹爪开度：`left/right_arm[7]`、`left/right_gripper[1]`；
- 语言 `l`；头部双目的内外参（`b≈58.25 mm`, `f≈282.4 px`, `rectified=true`）。

**未知但可一次标定**的量：手眼外参 `T_{c←e}`（腕部相机相对末端，刚性常数）。它把相机位姿写成

`T_{c←b}(t) = T_{e←b}(t) · T_{c←e}`。

> 关键：本赛题的“位姿估计”**不是估机器人**（白送），而是估**物体相对手/相机**的运动。腕部相机让后者变成一个带几何约束的残差检测问题。

### 1.2 定义 1 · 腕部自运动残差 WSR（Wrist Self-motion Residual）

取两个腕部帧 `I_t, I_{t+1}`，由已知末端位姿得到相机相对运动

`T_{t+1←t} = T_{c←b}(t)^{-1} T_{c←b}(t+1) = (R, τ)`。

对一对匹配点 `x ↔ x'`（齐次归一化像素坐标），若场景点静止，则满足对极约束

`x'^T [τ]_× R x = 0`。

定义其 **Sampson 残差**

`s(x,x') = (x'^T E x)^2 / ( ‖(Ex)_{1:2}‖^2 + ‖(E^T x')_{1:2}‖^2 )`，其中 `E=[τ]_×R`。

于是腕部独立运动集合为

`M_τ = { x : s(x, x') > θ_s }`，

并用 RANSAC 取最大一致静止集 `S*`，**残差集合 `M = M_τ \ S*` 就是“没有跟着手一起动”的像素**。定义 WSR 标量

`r_wsr(t) = ( |M| / |Ω| ,  median_{x∈M} s(x,x') ,  persist(M, Δt) )`。

**三个直接推论：**

1. `τ≈0`（纯旋转）时对极约束退化，改用单应/旋转诱导流残差：`H = R + (1/d) τ n^T`，或直接比较“已知旋转下的补偿光流”。
2. 若物体被**刚性夹持**，它相对相机静止，满足对极约束；因此**夹持物上出现高残差 = 滑动或被外力拿走/拧回**，这正是 `human_*` 撤回。
3. 若物体是**被推/被拨**的（非夹持），相对手运动是任务预期的；用技能/接触状态门控，只在“应静止”的子目标上启用 WSR。**WSR 不是万能异常检测，它是“相对刚体假设”的违背检测。**

### 1.3 定义 2 · 块级计分 MDP / POMDP

接口事实：`metadata.action_chunk_size = T_a` 固定，`get_action` 每次返回前导轴长 `T_a` 的动作块，评测端**整块执行后**再调用。因此决策epoch在块边界，天然是一个**块级 MDP**：

- 可观测状态 `o_t = (I^{head}_{t}, I^{wristL}_{t}, I^{wristR}_{t}, q_t, g_t, T_{e←b,t}, l)`；
- 隐藏事件 `e_t ∈ {无, 反向撤回, 拿走, 挪底座, 换物, 插入口移位, …}`（POMDP）；
- 动作 `A_t = (a_1..a_{T_a}) ∈ R^{T_a×d}`，外加离散**模式** `m_t ∈ {advance, recover, glance, fallback}`；
- 计分势函数 `Φ(o)` = “若此刻结束 episode，官方计分步已得分数”（0–100）+ `λ·1[success]`；
- **奖励 `r_t = γΦ(o_{t+1}) − Φ(o_t)`**（势函数塑形）。

**推导（本轮最关键的严格结论）**：

`Σ_{t=0}^{T-1} γ^t r_t = Σ_t γ^t (γΦ_{t+1} − Φ_t) = γ^T Φ_T − Φ_0`。

若 `Φ_0=0`，则**折扣回报 = γ^T · 最终步骤分**。取 `γ=1` 时，**最大化 RL 回报 ⇔ 最大化官方最终步骤分**，且势函数塑形不改变最优策略（Ng et al. 1999）。取 `γ<1` 则等价于**对后段进度打折**，会鼓励“先落袋为安、少冒险搏末步”——这正好对应 v2 发现的“末步分值恒 ≥ 前序、但可能被撤回”的风险结构。**奖励不是我们编的，是官方计分点直接给的。**

> 假设 A1（需手册确认）：步骤分按 **episode 最终状态**判定，因此撤回会真实丢分。若官方按“曾经达成”判定，则去掉 `Φ` 的下降项即可，框架不变。

### 1.4 定义 3 · 事后目标重标注 HGR（Hindsight Goal Relabeling）

一条成功演示 `τ=(o_0,a_0,…,o_T)`，其计分步完成时刻为 `t_1<…<t_K`。对任意 `i<t_k`，构造训练样本

`(o_i, g_k=o_{t_k}, a_{i:t_k}, R=1[reach(g_k) within ε])`。

- `i<t_k` 的 `o_i` 就是“第 k 步尚未完成/曾被退回”的状态；`o_i → o_{t_k}` 就是**恢复轨迹**。
- 真实人为撤回把物体拿到演示分布之外时，用仿真的扰动算子 `D` 生成 `o'_k = D(o_{t_k})`，再配对 `(o'_k, g_k)`。
- 于是 **HGR 覆盖“演示内可逆的退回”，DCR-RL（见 §4）覆盖“演示外的真实撤回”**，两者互补，不重叠。

**这不是数据增强的小技巧，而是把“恢复”从“需要失败样本”重新定义为“从任意早状态到达某个后状态”**——而后者在每条成功演示里都有 O(T²) 个。

### 1.5 定义 4 · 价值门控 VGC（Value-Gated Control）

训练一个块级评论家 `Q_ψ(o_t, A_t)`（仅离线/训练期使用，或作为共享骨干上的极小值头）。在线每个块边界：

`A_t* = argmax_{A∈C(o_t)} Q_ψ(o_t,A)  s.t.  latency(A)≤B,  smooth(A)≤S,  redo≤R,  WSR_override`。

候选集 `C = {advance(BC 先验), recover(目标条件), glance(主动注视), fallback(安全退回)}`。这把 v2 的手写状态机升级为**带硬安全约束的学得决策规则**；WSR 高置信时强制 `recover`，不让价值头“想继续搏分”。

## 2. 两个灵感词的解读

### 2.1 腕部相机：不是“多一路输入”，而是“相对运动的测量仪”

- **它测的是手-物关系，不是世界。** 头部相机回答“物体在桌上哪里”，腕部相机回答“物体相对我的夹爪偏了多少、滑没滑、被谁动了”。后者才是接触密集步（插网线、拉拉链、拧盖子、叠毛巾）真正决定成败的量。
- **它把 `human_*` 撤回变成几何事件。** 人把锁拿走、把拉链拉开、把叠好的毛巾翻开——在腕部帧里都表现为“局部区域违反了已知自运动下的对极约束”。**不需要“撤回长什么样”的标注，只需要“刚性场景应当怎么动”的约束。**
- **它天然对齐五个泛化轴中的三个：** 位置（眼在手上，物体绝对位置被消去）、背景（残差只看独立运动）、干扰物（独立运动分割）。对“未见物品”，运动残差与物体类别无关；但**语义进度**（这一步到底算不算完成）仍需语言/外观，这是它的边界。
- **它的边界必须说清：** 纯旋转时对极退化；接触瞬间运动模糊/遮挡最严重；透明、反光、形变、流体都会破坏“刚体”假设；手腕视角看不到全局布局。因此腕部相机必须与头部相机、关节本体感觉互补，不能单独当“真值”。

### 2.2 强化学习：在“不能在线试错”的赛制里，RL 只能离线 + 仿真 + 蒸馏

- **不能对真机在线 RL。** 提交物是固定策略，评测端只调用 `get_action`；没有奖励回传、没有梯度更新通道。任何“在线适应”都会伤可信度甚至违规。
- **但 RL 恰好适合这个计分结构。** 官方分数是“成功率 + 步骤分”，而步骤分是**有序、部分可观测、可被撤回**的。行为克隆只会模仿成功轨迹，不会学“什么时候该停下来核验、什么时候该重做、什么时候该放弃搏末步”。这些是**序贯决策**，正是 RL 的主场。
- **离线 RL 的三条数据腿：** ① 32k 成功演示（BC 先验 + HGR 重标注）；② 仿真扰动课程（DCR-RL，补真实撤回）；③ 价值门控的离线评估（用 GSO 当 critic 的裁判）。**部署只带 actor**，critic/奖励模型留在训练侧，规避“多模型”合规风险。
- **RL 的风险不是“学不会”，而是“学会作弊”。** 一旦用学得的 `Φ̂` 当奖励，策略会找 `Φ̂` 的盲区（例如反复做一个看起来像完成、实际没完成的动作）。因此能用解析计分谓词就用解析的；必须学时，用集成/不确定性惩罚 + 保守离线 RL + 真机锚点。

## 3. 瓶颈假设（v3 更新）

- **H1（最高杠杆）**：在零撤回样本下，**解析的腕部自运动残差**比学习式“撤回检测器”更可靠：前者只需要“刚性场景应如何运动”的物理约束，后者需要事件样本；且前者对位置/背景/干扰物天然不变。
- **H2**：恢复数据不必新采。**每条成功演示的“早状态 → 后子目标”都是恢复对**；HGR 能把 32k 演示变成百万级目标条件样本，足以先训出一个可用的恢复 actor。
- **H3**：在固定 `T_a` 的开环执行下，**块内发生的事只能通过 `obs_delta_indices` 的时序堆叠带回块边界**。把腕部图像与关节角按相同偏移一起堆叠，就能在**不改变 `T_a`、不增加决策次数**的前提下，把“块内被撤回”变成下一个块边界可反应的证据。
- **H4**：把奖励设为 `ΔΦ`（官方计分势）而不是手工 reward，能让 RL 的优化目标与榜单**同一个口径**；`γ` 是“先保前置分 vs 搏末步”的风险旋钮。
- **H5**：腕部 WSR 与计分谓词在**接触瞬间同时最不可靠**（遮挡/模糊/形变）。因此必须有一条**与腕部无关的兜底通道**（头部双目 + 关节/夹爪本体感觉 + 动作超时），否则“自信的残差错误”会引发反复重做。

## 5. 本轮最大风险（一句话）

**一句话**：腕部相机在最需要它的接触瞬间最容易遮挡、模糊、被形变/透明物体欺骗，而 RL 又会精准利用任何代理奖励的盲区——**若 WSR 与计分势在接触阶段同时失效，系统会学出“看起来在恢复、实际在刷步骤分”的伪策略**。

**→ 本轮最值得押注：`UIP-16 WSR × UIP-18 HGR × UIP-17 CRL` 组成的“腕部残差恢复闭环”，由 `UIP-01″` 在块边界调度**——它把 v2 最大的数据空白（人为撤回零覆盖）同时从**感知侧**（几何残差不需要样本）和**数据侧**（成功演示自带恢复对）绕开，且完全落在选手 API 权限与离线算力之内。

## 1. 旗舰深潜：UIP-01″ · WRRL（Wrist-Residual Recovery Loop）

### 1.1 数据流（在线）

```text
                 ┌─────────────── 离线训练（不带入提交物）───────────────┐
                 │  HGR: 成功演示 → (早状态, 后子目标) 恢复对            │
                 │  DCR-RL: 仿真注入撤回 → (撤回态, 子目标) 恢复对       │
                 │  CRL: r = γΦ(s') − Φ(s)，IQL/CQL + BC 先验           │
                 └──────────────────────────┬──────────────────────────┘
                                            │ 蒸馏
                                            ▼
  obs(4 图 + q + ee_pose + g + l) ──► 单 actor 骨干 ──► 动作块 A_t (T_a 步)
        │  (块边界)                          │
        │                                    ▼
        ├─► WSR：腕部自运动残差 ──────► 独立运动 mask / 滑动 / 被撤回
        ├─► 计分势 Φ̂ / 进度头 ────────► 当前子目标 done/ongoing/regressed
        └─► VGC：Q(o, A) 选模式 ──────► advance / recover / glance / fallback
```

**为什么叫“闭环”**：WSR 提供**免标注的异常证据**，CRL/HGR 提供**恢复动作**，VGC 提供**什么时候用哪条动作**的决策规则；三者共享同一套子目标/计分势定义（来自 v2 的 32 任务计分表）。

### 1.2 与 v2 旗舰的差异

| 维度 | v2 UIP-01′ | v3 UIP-01″ |
|---|---|---|
| `regressed` 判据 | 视觉/几何启发式，需“撤回长什么样” | **WSR：已知自运动下的对极/单应残差**，只需“刚性场景应如何动” |
| 恢复动作来源 | 手写“重做子目标” | **目标条件 actor（HGR+DCR-RL 训练）+ BC 先验** |
| 何时 advance/recover | 手写状态机 | **Q 值门控 + 硬安全约束** |
| 计分优化 | 手工“保前置、搏末步” | **奖励=ΔΦ，RL 直接优化官方步骤分** |
| 块长 | v2 假设运行期可变（❌） | **全局固定 `T_a`，块内堆叠取证**（✅） |

### 1.3 在线执行伪代码

```python
class WRRL_Policy:                      # UIP-01″/16/17/20/21 的部署外壳
    def __init__(self, actor, critic_head, wsr, task_graph, T_a,
                 gamma=0.97, redo_max=2, B_ms=200):
        self.actor, self.critic, self.wsr = actor, critic_head, wsr
        self.g = task_graph; self.T_a = T_a
        self.gamma = gamma; self.redo_max = redo_max; self.B = B_ms
        self.k = 0                      # 当前计分步索引
        self.redo = 0

    def reset(self):
        self.actor.reset(); self.wsr.reset()
        self.k = 0; self.redo = 0

    def get_action(self, obs):
        # 1) 块边界感知：WSR + 计分势（都用 obs_delta_indices 堆叠的若干帧）
        ev = self.wsr.evaluate(obs)                  # 独立运动 mask、滑动、持续帧数
        phi, state = self._score_potential(obs)      # Φ̂ 与 done/ongoing/regressed
        # 2) 硬安全：夹持物被撤回/滑脱 → 强制 recover
        forced = ev.held_object_moved and ev.conf > 0.7
        # 3) 候选动作块（同一 actor 的不同模式头/条件）
        cands = {
            "advance": self.actor(obs, mode="advance", goal=self.g.goal(self.k)),
            "recover": self.actor(obs, mode="recover", goal=self.g.goal(self.k)),
            "glance":  self.actor(obs, mode="glance",  goal=self.g.goal(self.k)),
            "fallback": self.actor(obs, mode="fallback"),
        }
        if forced:
            A = cands["recover"]
        else:
            A = max(cands.values(), key=lambda a: self.critic(obs, a))
        # 4) 安全阀：延迟/平滑/重做预算（UIP-15′）
        A = self._smooth_and_limit(A)
        # 5) 子目标推进
        if state == "done":
            self.k += 1; self.redo = 0
        elif state == "regressed" and self.redo < self.redo_max:
            self.redo += 1
        return A                                  # 前导轴长度恰为 T_a
```

## 2. UIP-16 · WSR（Wrist Self-motion Residual）

### 2.1 精确计算

输入：两帧腕部图 `I_t, I_{t+1}`；对应关节角 `q_t, q_{t+1}`；末端位姿 `T_{e←b,t}, T_{e←b,t+1}`；手眼 `T_{c←e}`。

```text
1. T_{c←b,t}   = T_{e←b,t}   · T_{c←e}
   T_{c←b,t+1} = T_{e←b,t+1} · T_{c←e}
2. T_{t+1←t}   = T_{c←b,t}^{-1} · T_{c←b,t+1} = (R, τ)
3. 特征匹配 x ↔ x'（ORB/LightGlue），RANSAC 估计：
     若 ‖τ‖ / d̄ > ε_parallax：对极模型 E=[τ]_×R，残差用 Sampson 距离 s(x,x')
     否则（近纯旋转）：单应模型 H=R+(1/d̄)τn^T，残差用重投影/补偿光流
4. 取最大一致静止集 S*；M = {s > θ_s} \ S*
5. 输出：
     frac_indep  = |M| / |Ω|
     mag_indep   = median_{x∈M} s(x,x')
     persist     = M 在连续 Δt 帧中重复出现的比例
     held_moved  = 夹持区域（由夹爪像素/手眼投影得到）内 frac_indep 高
```

### 2.2 三个必须处理的退化

1. **纯旋转**：`τ≈0` 时 `E` 退化，必须切到单应/旋转补偿模型；腕部“转腕看一眼”（UIP-21）恰好是纯旋转，若不切换会全屏误报。
2. **运动模糊/JPEG**：接触瞬间腕部帧常模糊；用多帧一致性 + 较高 `θ_s` + 时间持续 `persist` 压制瞬时噪声；JPEG q95/4:4:4 已尽量保真。
3. **非刚体/透明/反光**：毛巾、液体、透明瓶会破坏对极约束；这些任务把 WSR 降级为“**头部相机 + 夹爪开度 + 关节力矩（若可见）**”的兜底，不单独判 `regressed`。

### 2.3 为什么它“零样本”

对极约束的成立条件是**场景点相对相机静止**，它不依赖物体类别、不依赖“撤回长什么样”、不依赖训练分布。撤回/滑动之所以被检出，是因为它们**违反了这条物理约束**，而不是因为它们“看起来像撤回”。这与 v2 需要撤回正样本的检测器有本质区别。

## 3. UIP-17 · CRL（Chunk-level RL with Scoring Potential）

### 3.1 奖励推导（与榜单同口径）

设 `Φ(o)` 为“若此刻结束，官方计分步得分”（0–100；可加 `λ·1[success]`）。定义

`r_t = γΦ(o_{t+1}) − Φ(o_t)`。

则 `Σ_{t=0}^{T-1} γ^t r_t = γ^T Φ(o_T) − Φ(o_0)`。取 `Φ(o_0)=0`，折扣回报 `= γ^T · 最终步骤分`。

- `γ=1`：**精确等价于最大化最终步骤分**；
- `γ<1`：对后段进度打折，鼓励“先保前置、少冒险搏末步”，对应 v2 的“末步分值更大但可能被撤回”的风险结构；
- 势函数塑形**不改变最优策略**（Ng et al., 1999），所以这不是“手工 reward hack”，而是把官方计分表变成 RL 的势函数。

### 3.2 离线 RL 配方

- 数据：`D = D_demo ∪ D_HGR ∪ D_sim`。
- 算法：**IQL**（expectile 回归，不查询 OOD 动作）或 **CQL**（对 OOD 动作做悲观惩罚）；两者都对“成功演示偏置”更稳。
- BC 先验：`π_θ = argmax E[Q_ψ(o,A)] − β·KL(π_θ ‖ π_BC)`；`β` 从大到小退火，先“像人”，再“比人更会恢复”。
- 非对称 actor-critic：**critic 看仿真特权状态**（物体真位姿、扰动事件、接触力），**actor 只看可部署观测**（4 图 + q + ee_pose + g + l）。部署只带 actor。
- 训练目标：块级回报；`T_a` 作为全局超参在仿真里扫（见 §7.1），不参与在线决策。

### 3.3 与行为克隆的分工

| 能力 | BC | CRL |
|---|---|---|
| 复现成功轨迹 | 强 | 作为先验保留 |
| 判断“是否被撤回” | 无 | 由 Φ/WSR 提供信号 |
| 决定“继续 vs 重做 vs 放弃” | 无 | Q 值直接优化 |
| 优化步骤分而非动作相似度 | 无 | 奖励=ΔΦ |
| 风险偏好（γ） | 无 | 可调 |

## 4. UIP-18 · HGR（Hindsight Goal Relabeling）

### 4.1 构造算法

```python
def build_hgr(demos, subgoal_times, epsilon):
    D = []
    for tau in demos:                      # tau = [(o_i, a_i, q_i, ee_i)]
        for k, t_k in enumerate(subgoal_times[tau.task]):
            g_k = tau[t_k].obs            # 子目标完成时的观测（可加相对位姿/可供性）
            for i in range(t_k):           # 任意更早状态
                D.append(Transition(
                    o=tau[i].obs, goal=g_k,
                    action_seq=tau[i:t_k].actions,
                    reward=1.0,            # 到达 g_k
                    discount=1.0,
                ))
    return D
```

### 4.2 三种“恢复对”的来源

| 来源 | 起点 `o` | 目标 `g` | 覆盖的撤回类型 |
|---|---|---|---|
| **HGR-early** | 同一演示中更早的状态 `o_i, i<t_k` | `o_{t_k}` | 机器人自己尚未完成 / 被可逆地退回 |
| **HGR-cross** | 同任务其它 episode 的同相位状态 | `o_{t_k}` | 初始位置/物体差异带来的“近似退回” |
| **DCR-sim** | 仿真中对 `o_{t_k}` 施加扰动算子 `D` 后的状态 | `o_{t_k}` | 真实 `human_*`：拿走、拧回、翻开、拉开、挪底座、换物 |

### 4.3 为什么这不是“数据增强的小把戏”

它改变的是**问题的定义**：恢复不需要“失败样本”，只需要“目标状态”和“任意更早状态”。而每条成功演示天然提供 O(T²) 个“早状态 → 后子目标”对。**这是把“零撤回数据”从不可解变成可解的关键一步。** 局限是：HGR 只能覆盖“演示分布内的退回”；分布外的真实撤回（人把物体拿到别处）必须靠 DCR-RL 的仿真课程补。

## 5. UIP-19 · DCR-RL（Disturbance Curriculum RL）

### 5.1 扰动类型（与 32 任务 `human_*` 对应）

| 类型 | 例子（v2 §2 已核实） | 仿真实现 |
|---|---|---|
| `reverse` 反向撤回 | T14 拧开后再拧回、T19 拉上后再拉开、T16 叠好后翻开 | 对关节/物体施加反向位姿轨迹 |
| `take_away` 拿走 | T12 中途把锁拿走、T27 叠第二后拿下第二 | 物体瞬移/机械手抓走 |
| `move_base` 挪底座/物体 | T25 放第一个后挪底座、T08 抓书后挪架子 | 物体/支架随机平移 |
| `swap` 换物 | 未见物体轴（`unseen_object_*`） | 同类不同实例替换 |
| `occlude` 遮挡/插入口移位 | T26 插口移开、T10 拔起插头 | 目标位姿/可见性随机化 |

### 5.2 课程（由易到难）

1. **无扰动**：先让 actor 在仿真里追平 BC 基线；
2. **边界扰动**：只在子目标完成瞬间施加撤回（最容易学“检测 + 重做”）；
3. **块内扰动**：在动作块执行中途施加，训练“块边界才发现”的延迟反应；
4. **对抗时机**：用一个小 adversary 选择扰动时机/幅度，最大化“步骤分损失”；
5. **组合扰动**：撤回 + 物体位移 + 相机噪声同时出现。

### 5.3 域随机化（sim-to-real）

物体位姿/尺度/纹理、光照/色温、腕部相机手眼外参微扰、JPEG 压缩、运动模糊、控制延迟、夹爪摩擦。**关键是把手眼外参误差也随机化**，让 WSR 对“标定不完美”鲁棒，而不是在仿真里假设完美外参。

## 6. UIP-20 VGC / UIP-21 WAG / UIP-22 SRC

### 6.1 UIP-20 · VGC（价值门控）

- 候选模式：`advance`（BC 先验）、`recover`（目标条件恢复）、`glance`（主动注视）、`fallback`（安全退回/松手重抓）。
- 选择：`argmax Q_ψ(o,A)`，硬约束：`latency≤B`、`‖Δa‖≤S`、`redo≤R`、WSR 高置信强制 `recover`。
- 与 v2 状态机的区别：**状态机只回答“现在是不是 regressed”；VGC 还回答“为了多拿步骤分，值不值得花一个块去核验/重做”**——这是 RL 才能给的序贯价值。

### 6.2 UIP-21 · WAG（腕部主动注视 / gaze-as-action）

- 动作空间天然包含末端姿态（`ee` 模式 6D 含 `rpy`；`joint` 模式含腕部 3 关节），所以“转腕看一眼”是合法动作。
- 目标：在接触前把腕部转到能最大程度看清“对位/齿合/插入深度”的视角；用信息增益（熵下降）或 WSR 可辨识度作为辅助奖励。
- 约束：纯旋转会让对极退化（§2.2），所以 WAG 必须与单应/旋转补偿模型配套；且注视耗时，只在接触前用。

### 6.3 UIP-22 · SRC（腕部 sim-real 校准）

- **手眼**：离线 `AX=XB` 标定 `T_{c←e}`；在线用静止背景的对极约束做小幅精化（可选）。
- **内参/畸变**：直接用 `camera_params`（左/右各有彩色内参与 `inverse_brown_conrady`）。
- **光度**：腕部近距，sim-to-real 差距主要来自高光、阴影、接触形变，不是全局位姿；用光度随机化 + 真实腕部帧做风格对齐。
- **验收**：在 GSO-W 里比较“仿真腕部 WSR 分布”与“真机腕部 WSR 分布”，用分布距离（如 Wasserstein）而非像素差做校准指标。

## 7. 实时性与接口工程（含 v2 的硬修正）

### 7.1 修正：`action_chunk_size` 是全局常数

官方 README §1/§3：`action_chunk_size` 在 `metadata` 中声明，`get_action` 返回的**每个动作数组前导轴长度都是 `T_a`**；评测端整块执行后再调用。因此：

- ❌ v2 `UIP-13 ACS` 的“按阶段运行期选 k”不成立；
- ✅ 正确做法：**离线用一个全局 `T_a`**，把“反应性”交给**块边界重观测 + 块内时序堆叠 + 块内平滑插值**。
- `T_a` 的候选：`{1,2,4,8,16}`。小 `T_a` = 高反应性、高往返/带宽/延迟暴露；大 `T_a` = 低开销、低反应性。用仿真 + 真机锚点扫，指标=步骤分 / 延迟方差 / 带宽。

### 7.2 用 `obs_delta_indices` 把“块内发生的事”带回块边界

这是本轮最重要的工程技巧：**不改变 `T_a`、不增加决策次数**，只靠时序堆叠，就能在下一个块边界看到“上一个块执行期间腕部发生了什么”。

```python
metadata = {
    "control_space": "ee",                 # 或 joint
    "obs_delta_indices": {
        "observation.language":                    [0],
        "observation.images.cam_left_wrist":       [-2, 0],   # 2 帧腕部
        "observation.images.cam_right_wrist":      [-2, 0],
        "observation.images.cam_left_high":        [0],       # 头部 1 帧（可降分辨率）
        "observation.images.cam_right_high":       [0],
        "observation.state.left_arm":              [-2, 0],   # 与腕部同偏移，供 FK/自运动补偿
        "observation.state.right_arm":             [-2, 0],
        "observation.state.left_gripper":          [-2, 0],
        "observation.state.right_gripper":         [-2, 0],
        "observation.state.left_ee_pose_gripper_base":  [0],
        "observation.state.right_ee_pose_gripper_base": [0],
    },
    "image_resize": {
        "observation.images.cam_left_high":  [240, 320],
        "observation.images.cam_right_high": [240, 320],
        # 腕部保持原生 480x640，保住接触细节
    },
    "action_chunk_size": 4,
    "token": token,
}
```

**注意**：`obs_delta_indices` 的 key 决定“发送哪些观测”，value 决定“堆叠几帧”。每一帧图像都是一张 JPEG（q95、4:4:4），所以堆叠是**线性加带宽**的。腕部保原生、头部降分辨率，是把带宽花在刀刃上。

### 7.3 带宽/延迟粗算（需实测校准）

- JPEG q95 4:4:4 的 480×640 自然图像约 `60–120 KB/帧`；240×320 约 `15–30 KB/帧`。
- 上述配置每块：腕部 `2×2=4` 帧 × ~90 KB ≈ 360 KB；头部 `2×1` 帧 × ~25 KB ≈ 50 KB；其余状态可忽略 → ~0.4 MB/块。
- `T_a=4`、数据 30 fps ⇒ ~7.5 次/秒 ⇒ ~3 MB/s；`T_a=8` ⇒ ~1.5 MB/s。
- **反应延迟**：`T_a=4` ≈ 133 ms 一个块；`T_a=1` ≈ 33 ms，但带宽/往返 ×4。**块内堆叠让“发现撤回”的延迟≈一个块，而不是“等到下下个块”。**

> 评测控制频率 README 未写死（数据侧 30 fps）；上面按 30 Hz 估算，需用官方 client 实测。

### 7.4 N 端口

- 共享一条骨干 + **每端口 KV/历史/WSR 状态隔离**（v2 UIP-08′）。
- 请求批处理可选：N 个端口同时到达时合并前向；但必须保证每端口 `reset()`、隐藏状态、WSR 基准帧互不污染。
- 延迟稳定性：避免在 `get_action` 里做同步标定/大模型加载；所有离线产物在启动时加载完毕。

## 8. 关键伪代码

### 8.1 WSR 评估（含退化切换）

```python
def wsr(I0, I1, q0, q1, ee0, ee1, T_ce, K, theta_s, eps=1e-3):
    T_cb0 = ee0 @ T_ce
    T_cb1 = ee1 @ T_ce
    R, tau = relative(T_cb0, T_cb1)
    pts0, pts1 = match_features(I0, I1)          # 例如 LightGlue
    if norm(tau) / mean_depth_prior > eps:
        E = skew(tau) @ R
        s = sampson(pts0, pts1, E, K)
        inlier = s <= theta_s
    else:                                        # 近纯旋转
        H = R + outer(tau, n_prior) / mean_depth_prior
        s = reproj_error(pts0, pts1, H, K)
        inlier = s <= theta_s
    static = robust_consensus(inlier)            # RANSAC / M-estimator
    indep = (~static) & (s > theta_s)
    return {
        "frac": indep.mean(),
        "mag": median(s[indep]) if indep.any() else 0.0,
        "held_moved": held_region_fraction(indep) > 0.3,
    }
```

### 8.2 计分势与奖励

```python
def phi(obs, task, verifier):
    s = 0
    for k, step in enumerate(task.scoring_steps):
        if verifier.done(obs, step):     # 解析谓词优先；否则 Φ̂
            s += step.points
    return s + task.lambda_success * float(verifier.success(obs))

def reward(o, o_next, task, verifier, gamma):
    return gamma * phi(o_next, task, verifier) - phi(o, task, verifier)
# 若官方按“曾经达成”判分（A1 不成立），去掉负项：
# return max(0.0, phi(o_next) - phi(o))
```

### 8.3 事后重标注 + 仿真扰动

```python
def relabel_with_disturbance(demo, t_k, D, goal):
    o_goal = demo[t_k].obs
    samples = [Sample(o=demo[i].obs, goal=o_goal, actions=demo[i:t_k],
                      reward=1.0)
               for i in range(t_k)]                    # HGR-early
    o_reg = D(o_goal)                                   # 仿真施加真实撤回
    samples.append(Sample(o=o_reg, goal=o_goal,
                          actions=recover_actions(o_reg, o_goal),
                          reward=1.0))                  # DCR-sim
    return samples
```

| 实验 | 对照 | 指标 | 目标 |
|---|---|---|---|

## 10. 合规、风险与时间线

### 10.1 合规

- **单模型**：提交物只带**一个 actor 骨干**；critic、HGR/DCR 训练管线、奖励模型全部留在训练侧。WSR 是**解析几何模块**（无可学习参数），不算“第二个模型”。若评测对“模型”定义严格，连值头也可以去掉（VGC 退化为固定规则）。
- **不做在线更新**：`get_action` 内不训练、不回传、不改参数；`reset()` 只清状态。
- **不引入外部大模型推理**：外部 VLM/6D 基础模型有“非单模型”与延迟风险，封存。
- **接口红线**：动作数组前导轴严格 `T_a`；dtype/token/键名严格按 README；动作统计保持平滑，避免可信度异常。

### 10.2 主要风险与缓解

| 风险 | 表现 | 缓解 |
|---|---|---|
| WSR 在接触瞬间失效 | 遮挡/模糊/形变 → 漏检或误报 | 多帧 persist + 头部/夹爪兜底 + 高阈值时保持 ongoing |
| RL 利用代理奖励盲区 | “看起来在恢复，实际刷分” | 解析谓词优先 + 集成不确定性惩罚 + 保守离线 RL + GSO 裁判 |
| 仿真过拟合 | sim 步骤分涨、真机不涨 | GSO-W 只当结构裁判 + 真机锚点 + 外参/光度随机化 |
| 固定 `T_a` 的两难 | 反应性 vs 延迟/带宽 | 离线全局扫描 + 块内堆叠取证 + 头部降分辨率 |
| HGR 覆盖不足 | 演示外撤回学不到 | DCR-RL 补分布外；对抗时机课程 |
| 单模型合规 | 多模块被判违规 | 只带 actor；解析 WSR；训练侧组件不进提交物 |

### 10.3 时间线（粗排）

- **第 1–2 周**：手眼标定 + WSR 原型；在公开腕部视频上验证“静止段残差≈0、注入扰动段残差↑”。选 5 个代表任务：T26 插网线、T19 拉链、T16 叠毛巾、T27 叠碗、T14 拧盖。
- **第 3–4 周**：HGR 数据管线（子目标时刻标注 + 目标条件样本）；BC 先验复现。
- **第 5–6 周**：CRL（IQL/CQL）离线训练；GSO-W 计分势校准；`T_a` 扫描。
- **第 7–8 周**：DCR-RL 扰动课程 + 非对称 actor-critic；VGC/WAG 接入；多端口压测。
- **第 9 周起**：真机锚点校准 WSR 阈值、`γ`、`T_a`；以榜单/步骤分迭代。

## 11. 本轮最大风险 & 押注

**一句话**：腕部相机在最需要它的接触瞬间最容易遮挡/模糊/被形变与透明物体欺骗，而 RL 会精准利用任何代理奖励的盲区——若 WSR 与计分势在接触阶段同时失效，系统会学出“看起来在恢复、实际在刷步骤分”的伪策略。

**→ 押注：`UIP-16 WSR × UIP-18 HGR × UIP-17 CRL` 的“腕部残差恢复闭环”**——它同时绕开 v2 的两个死结：**撤回检测不需要撤回样本（几何约束）**，**恢复训练不需要恢复数据（成功演示自带恢复对）**；再用 `UIP-01″` 的块边界价值门控把两者接成一个可部署的单模型闭环。
