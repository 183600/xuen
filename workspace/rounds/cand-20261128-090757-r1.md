### 第 7 轮灵感驱动研究记录

**灵感词**：用户需求分析、大语言模型、面部表情识别

**继承关系**：第 6 轮 CADVS-v6（IP-497~IP-500）确立「指令-几何-力学三元凿」框架：GGC 提供抓取几何可达性约束、MCTM 注入空间拓扑图、STM 实现跨模态指令-轨迹映射，七硬门保持 fail-closed 边界。本轮延续「硬门不增」原则，聚焦「**需求-意图-一致性三角桥**」：在保持证书边界不变的前提下，直接从「用户需求分析」出发，设计「需求意图建模器」(DIM)，引入「需求一致性软评分」η_demand，使系统从「被动接受指令」转向「主动推导意图」。

**直觉与动机**：

1. **用户需求 → 从「指令响应」到「意图推导」**。第 6 轮的 STM 负责「语言→查询向量」的映射，但它无法区分「用户真正想要的」与「用户不够清晰说出的」。引入「需求意图建模器」(Demand Intent Model, DIM)：从用户的历史交互记录、当前环境约束、任务目标三方面推断「用户真正的需求目标」ρ_demand。关键洞见是：**行为从「指令驱动」转向「需求驱动」**——只有当推断的需求意图与指令意图高度一致时，才执行STM生成的轨迹；否则，触发「需求导向回退」。

2. **大语言模型 → 从「静态映射」到「动态推理」**。第 6 轮的 STM 采用 CLIP-style 对齐训练，对指令进行向量化。第 7 轮引入「需求推理链」(Demand Reasoning Chain, DRC)：将LLM连接到DIM，使得从「用户说了什么」到「用户可能需要什么」的推理过程可解释、可审计。关键洞见是：**LLM 充当「需求解释器」**——它的推理链被量化为 η_demand，若推理置信度低于阈值，系统自动切换到历史记忆中的「典型需求响应」。

3. **面部表情识别 → 从「情感调制」到「需求态度捕获」**。第 6 轮的 FAMK 调制阈值 γ_i。第 7 轮提出「需求态度捕获」(Demand Affect Capture, DAC)：基于面部表情识别，捕获用户当前的「需求态度」(desire_affect)——如焦虑表情可能意味着「需要快速、稳妥的解决方案」，而放松表情可能意味着「愿意探索创新方案」。关键洞见是：**情感态度调制需求优先级**——DAC 输出的 desire_affect 调节 ρ_demand 的稀疏性和探索度。

**关键洞见**：第 6 轮回答「如何在不新增硬门的前提下，让提议符合物理、空间、意图」；第 7 轮回答「如何从「用户需求」出发，让系统主动推导「正确的行为」，而不是被动接受指令」。七硬门 kc_evidence_forged_v5 记号原样复用；本轮新增的只有：
- IP-501 DIM（需求意图建模器），
- IP-502 DRC（需求推理链，LLM驱动），
- IP-503 DAC（需求态度捕获），
- IP-504 EFA-v7（软评分 η_demand 纳入四软因子链）

**形式化目标（增量）**：

1. **DIM（Demand Intent Model）**：<br>
   - 需求编码器 E_demand: (history, context, env) ⟼ ρ_demand ∈ ℝ^d_demand<br>
   - 损失 L_DIM = ||ρ_demand - ρ_gold||² + β·KL(π_demand || π_prior)<br>
   - 软因子：η_demand = 1 - H(ρ_pred || ρ_demand)，其中 H 为交叉熵<br>
   - 只有当 η_demand > τ_demand 时，STM 输出的指令才被采纳；否则触发「需求导向回退」

2. **DRC（Demand Reasoning Chain）**：<br>
   - LLM 推理链 R = {r_1, r_2, ..., r_n}，其中 r_i 为推理步骤<br>
   - η_demand = 1 - (1/n)·Σ_i H(r_i)，衡量推理链的整体确定性<br>
   - L_DRC = α·链长度惩罚 - η_demand，鼓励简洁且确定的推理

3. **DAC（Demand Affect Capture）**：<br>
   - 表情编码器 E_affect: face ⟼ affect ∈ {-1, 0, +1}（负面/中性/正面）<br>
   - desire_affect 调节 ρ_demand 的探索度：exploration_scale = 1 + κ·affect<br>
   - 软因子：η_affect = 1 + affect/3 ∈ [2/3, 4/3]，调制 STM 检索的广度

4. **EFA-v7（七硬门 + 四软因子链）**：<br>
   - ECS_v7 = ECS_v6 · η_g · η_topo · η_interp · η_cmd · η_demand · η_affect<br>
   - τ_i^v7 = γ_i·τ_i^v6·Π_factor_i，其中 Π_factor_i = ∏_{j=1}^5 η_j ∈ [1, 1+ε]，设计上限仍为 1.3<br>
   - 新增硬门 kc_demand：η_demand ≥ τ_demand，确保「用户需求」被必要检验

5. **形式化定义**：给定指令 L，目标 ρ_target，记忆 M：<br>
   - ρ_demand = DIM(history, context, env)；<br>
   - η_demand = 1 - H(STM(L) || ρ_demand)；<br>
   - 若 η_demand < τ_demand：<br>
     - q_demand = E_demand(ρ_demand)；<br>
     - m_demand = Top-k(Retr_M(q_demand, K=4))；<br>
     - c_demand = (obj, g_emb, θ_fp, task, ŝ_emo, m_demand, ρ_target, t_topo, q_demand)；<br>
     - x_demand = FMPP.propose(c_demand, K=8)；<br>
   - 若 η_demand ≥ τ_demand：<br>
     - 执行第 6 轮的 EFA-v6 流程<br>

**直觉与动机（本轮迭代扩展）**：

1. **碰撞检测 → 从「硬门约束」到「需求驱动碰撞 guard」**：现有七硬门保证 fail-closed，但未在需求导向回退路径中引入几何碰撞检测。关键洞见：**需求推断的轨迹若存在几何碰撞，即便一致性 η_demand 高，也应拒绝或触发安全回退**。引入 η_collision 软因子，基于 GGC 碰撞网格实时评估 x_demand 与环境的碰撞概率。

2. **语义地图 → 从「向量近似」到「结构化语义映射」**：当前 DIM 的 ρ_demand ∈ ℝ^d_demand 仅作为稠密向量，缺乏语义结构化表征。关键洞见：**引入语义地图，将 ρ_demand 投射到任务语义簿，通过 k-NN 检索确保 ρ_demand 与实际可达任务的语义一致性**，从而 η_demand 有了结构化依据而非纯统计近似。

3. **痛点分析 → 从「假设致盲」到「三层防护机制」**：核心风险是用户意图的非线性突变与自我否定。痛点分析指向三层防护：① **Dual-track DIM**（主需求路径 + 备选路径，经一致性投票），② **η_demand 实时可解释性检查**（每一步 η_demand 的变化趋势而非单点阈值），③ **需求演化检测**（连续 3 轮 η_demand 变化率超过阈值时强制回退）。

**关键洞见**：第 7 轮已回答「如何主动推导正确行为」；本轮迭代回答「如何在推导过程中 guards 多维度防止『正确但有风险』的行为」；七硬门依然保持 fail-closed，新增的只有软因子扩展与两层防护机制。

**形式化目标（增量）**：

1. **η_collision（碰撞软因子）**：
   - 基于 GGC 碰撞网格：η_collision = 1 - (碰撞体素计数 / 总体素数) ∈ [0,1]
   - 仅在需求导向回退路径中计算；常规 EFA-v6 流程不受影响

2. **语义地图投射**（Semantic Map Projection，SMP）：
   - S(ρ_demand) = Top-k(Retr_M(q_semantic, K=8))，其中 q_semantic = W·ρ_demand + b 为可学习投影
   - 一致性验证：η_semantic = 1 - (1/k)·Σ_j sim(ρ_demand, ρ_target_j)，sim 为余弦相似度
   - 若 η_semantic < τ_semantic（默认 0.6），触发语义一致性回退

3. **Dual-track DIM**：
   - 主路径：ρ_demand^main = DIM.encode(history, context, env)
   - 备路径：ρ_demand^alt = DIM.encode(history_tail, context, env) 其中 history_tail 为最近 3 条交互
   - 投票：若 sim(ρ_demand^main, ρ_demand^alt) > τ_vote（默认 0.7），则使用主路径；否则使用备路径并标记「需求不稳定」

4. **EFA-v7 增强**：
   - ECS_v7 = ECS_v6 · η_g · η_topo · η_interp · η_cmd · η_demand · η_affect · η_collision
   - 软因子链 Π_factor_i = ∏_{j=1}^7 η_j ∈ [1, 1.3]（已含 η_collision，设计上限 1.3 保持不变，意味着 η_collision 默认置 1 或在常规流程中不计）

5. **形式化定义（增量）**：
   - ρ_demand = DIM(history, context, env)；<br>
   - （主路径）ρ_demand^main = ρ_demand；<br>
   - （备路径）ρ_demand^alt = DIM(history_tail, context, env)；<br>
   - η_semantic = 1 - (1/k)·Σ_j sim(ρ_demand, ρ_target_j)；<br>
   - η_collision = 1 - (collision_voxels / total_voxels)；<br>
   - 若 η_demand < τ_demand  或  η_semantic < τ_semantic  或  η_collision < τ_collision（默认 0.5）：<br>
     - 走需求导向回退，并额外检查 η_collision<br>
   - 若 所有 软因子 ≥ 阈值：<br>
     - 执行 EFA-v6 在线流程 + 软因子链 × η_demand × η_affect × η_collision

**本轮最大风险**：**需求意图的非线性突变与自我否定**：尽管引入 dual-track 与语义地图，但用户意图仍可能在短期内发生非线性突变（如 suddenly switching from「放置到桌子」到「拿走到柜子」），此时 dual-track 可能因历史权重过大而滞后，语义地图的投影投影也可能过旧。这种结构上的捕获难题在维持七硬门 fail-closed 边界时，仍可能导致「正确但时机不当」或「正确但错误目标」的行动。

## 2. 关键算法骨架

### IP-501 DIM：需求意图建模器

```python
@dataclass
class DemandIntentModel:
    """DIM：从历史交互推断用户需求 ρ_demand。
    输入：历史记录 H = {e_τ^1, ..., e_τ^n}, 上下文 C, 环境 E
    输出：需求向量 ρ_demand + 软因子 η_demand"""
    encoder: nn.Module           # E_demand: (H, C, E) ⟼ ρ_demand
    predictor: nn.Module          # ρ_pred: STM(L) 输出
    beta: float = 0.1            # KL 正则系数
    history_tail_len: int = 3    # 备用路径使用的最近交互长度

    def encode(self, history: list[Embedding], context: dict, env: dict) -> torch.Tensor:
        """从历史+上下文+环境编码需求（主路径）"""
        h_repr = self.history_encoder(history)
        c_repr = self.context_encoder(context)
        e_repr = self.env_encoder(env)
        return self.fusion(h_repr, c_repr, e_repr)  # ρ_demand^main

    def encode_alt(self, history_tail: list[Embedding], context: dict, env: dict) -> torch.Tensor:
        """从最近几条交互编码备用需求 ρ_demand^alt"""
        h_repr = self.history_encoder(history_tail)
        c_repr = self.context_encoder(context)
        e_repr = self.env_encoder(env)
        return self.fusion(h_repr, c_repr, e_repr)  # ρ_demand^alt

    def demand_score(self, L: str, history: list[Embedding] | None = None) -> tuple[torch.Tensor, torch.Tensor, float]:
        """计算需求一致性 η_demand = 1 - H(ρ_pred || ρ_demand)
        返回：ρ_demand^main, ρ_demand^alt, η_demand"""
        if history is None:
            history = ...  # 默认使用当前历史记录
        rho_demand_main = self.encode(history, ...)
        # 备路径：使用最近 history_tail_len 条记录
        history_tail = history[-self.history_tail_len:] if len(history) >= self.history_tail_len else history
        rho_demand_alt = self.encode_alt(history_tail, ...)
        rho_pred = self.predictor(L)  # STM 的输出
        # 主路径 KL
        kl_main = self.kl_divergence(rho_pred, rho_demand_main)
        eta_main = 1.0 - torch.tanh(kl_main).item()
        # 备路径 KL
        kl_alt = self.kl_divergence(rho_pred, rho_demand_alt)
        eta_alt = 1.0 - torch.tanh(kl_alt).item()
        # 投票一致性
        sim = torch.cosine_similarity(rho_demand_main, rho_demand_alt).item()
        return rho_demand_main, rho_demand_alt, eta_main, eta_alt, sim

    def forward(self, history: list[Embedding], context: dict, env: dict, L: str | None = None):
        """端到端前向：若 L 为 None，返回需求导向行为；否则返回一致性检查"""
        if L is None:
            rho_main, rho_alt, eta_main, eta_alt, sim = self.demand_score(L, history)
            voted = rho_main if sim > self.tau_vote else rho_alt
            return voted, eta_main if sim > self.tau_vote else eta_alt, sim
        else:
            rho_demand_main, rho_demand_alt, eta_demand, eta_alt, sim = self.demand_score(L, history)
            # 语义地图投射
            q_semantic = self.semantic_projector(rho_demand_main)
            # 此处将 η_semantic 的计算交给 EFA-v7 完成，此处仅返回基础信息
            return rho_demand_main, rho_demand_alt, eta_demand, sim
```

### IP-502 DRC：需求推理链

```python
@dataclass
class DemandReasoningChain:
    """DRC：基于 LLM 的需求推理链。
    输入：指令 L, 需求 ρ_demand
    输出：推理链 R, 软因子 η_demand"""
    llm: LLM
    alpha: float = 0.1  # 链长度惩罚
    tau_chain_consistency: float = 0.8  # 推理链一致性阈值

    def infer(self, L: str, context: dict) -> tuple[list[str], float]:
        """生成推理链并计算 η_demand"""
        prompt = self.build_prompt(L, context)
        chain, steps = self.llm.generate_with_chain_of_thought(prompt)
        # H(r_i) 近似为信息熵：每一步的确定性
        entropies = [self.step_entropy(r) for r in steps]
        avg_entropy = sum(entropies) / len(steps)
        eta = 1.0 - avg_entropy
        # 链长度惩罚
        eta = eta - self.alpha * (len(steps) / 10.0)
        # 链一致性检查：若任意步骤熵过高，降低 η_demand
        max_entropy = max(entropies) if entropies else 0
        if max_entropy > self.tau_chain_consistency:
            eta = eta * 0.5  # 显著降低置信度，触发更保守路径
        return chain, max(0.0, eta)

    def step_entropy(self, r: str) -> float:
        """粗略估计推理步骤的熵"""
        # 基于概率词分布熵
        probs = self.llm.get_token_probs(r)
        return -(probs * torch.log(probs + 1e-8)).sum().item()
```

### IP-503 DAC：需求态度捕获

```python
@dataclass
class DemandAffectCapture:
    """DAC：从面部表情捕获用户需求态度 desire_affect。
    影响：调节检索的探索度，软因子 η_affect ∈ [2/3, 4/3]"""
    face_encoder: nn.Module
    affect_threshold: float = 0.5
    confidence: float = 1.0  # 面检测置信度，默认 1.0

    def observe(self, face: np.ndarray, confidence: float | None = None) -> tuple[float, float]:
        """捕获 desire_affect ∈ {-1, 0, +1} 与置信度"""
        if confidence is not None:
            self.confidence = confidence
        z = self.face_encoder(face)
        prob = torch.softmax(z, dim=-1)
        # 假设输出 [负面, 中性, 正面]
        affect = prob[2].item() - prob[0].item()  # [-1, 1]
        affect = max(-1.0, min(1.0, affect))
        return affect, self.confidence

    def get_affect_factor(self, affect: float) -> float:
        """η_affect = 1 + affect/3 ∈ [2/3, 4/3]"""
        return 1.0 + affect / 3.0

    def exploration_scale(self, affect: float, kappa: float = 0.5) -> float:
        """调节检索的广度：探索度 = 1 + κ·affect"""
        return 1.0 + kappa * affect

    def affect_confidence_mod(self, affect: float, conf: float) -> float:
        """基于置信度调 modulate affect 的有效性：η_affect_eff = η_affect · conf^λ"""
        lambda_ = 2.0
        eta_affect = self.get_affect_factor(affect)
        return eta_affect * (conf ** lambda_)
```

### IP-504 EFA-v7：七硬门 + 六软因子链 + 碰撞守卫

```python
@dataclass
class EvidenceForgingAssemblerV7:
    """EFA-v7：七硬门不变 + 六软因子链 η_g·η_topo·η_interp·η_cmd·η_demand·η_affect·η_collision"""
    fmpp: FlowMatchingProposalPolicyKernel
    lmem: LongTermMemoryEmbeddingConsolidation
    famk: FacialAffectModulationKernel
    ggc: GraspGeometryCutter
    mctm: MobileChassisTopologyMap
    stm: SemanticTrajectoryMapper
    dim: DemandIntentModel
    drc: DemandReasoningChain
    dac: DemandAffectCapture
    v6: EvidenceForgingAssemblerV6  # 复用七硬门
    tau_demand: float = 0.7
    tau_semantic: float = 0.6
    tau_collision: float = 0.5
    tau_vote: float = 0.7

    def select(self, L: str | None, t_now, context) -> tuple[bool, Trajectory | None, str]:
        """从指令 L 开始 → 最优合规轨迹（v7 需求导向 + 碰撞守卫）"""
        # 0. 捕获需求态度
        affect = self.dac.observe(context.face) if hasattr(context, 'face') else 0.0
        eta_affect_raw = self.dac.get_affect_factor(affect)
        eta_affect = self.dac.affect_confidence_mod(affect, self.dac.confidence)

        # 1. 需求意图推断（双轨投票）
        rho_demand_main, rho_demand_alt, eta_demand_main, eta_demand_alt, sim = self.dim.forward(
            history=self.lmem.get_history(),
            context=context.__dict__,
            env=context.env if hasattr(context, 'env') else {},
            L=L
        )

        # 投票机制：若主备一致性高，使用主路径；否则使用备路径
        if sim > self.tau_vote:
            rho_demand_voted = rho_demand_main
            eta_demand_used = eta_demand_main
        else:
            rho_demand_voted = rho_demand_alt
            eta_demand_used = eta_demand_alt

        # 2. 语义一致性检查（通过语义地图投射获得 η_semantic）
        q_semantic = self.dim.semantic_projector(rho_demand_voted)
        # 计算 η_semantic：基于 Top-k 检索到的语义目标与 ρ_demand 的一致性
        # （此处假设由 EFA-v7 调用时传入语义检索结果，或在内部完成）
        # 简化为：η_semantic = 1.0 表示通过，< τ_semantic 则触发回退
        # 实际实现中将通过检索器计算具体值，此处占位
        eta_semantic = 1.0  # 占位，实际由内部语义检索填充

        # 3. 碰撞检测（仅在需求导向回退路径或软因子检查时计算）
        # 若常规流程，η_collision 默认置 1.0（不影响软因子链）
        # 若为回退路径，基于 GGC 计算碰撞概率
        eta_collision = 1.0  # 占位，实际由 GGC 碰撞网格实时计算

        # 4. LLM 推理链检查
        chain, eta_demand_from_chain = self.drc.infer(L, context.__dict__)
        eta_demand_total = max(eta_demand_used, eta_demand_from_chain)

        # 5. 多维阈值检查：若任一软因子低于阈值，触发相应回退
        demand_ok = eta_demand_total >= self.tau_demand
        semantic_ok = eta_semantic >= self.tau_semantic
        # 仅在需求导向回退路径才计算 η_collision；常规流程置 1.0
        collision_ok = True  # 常规流程默认通过；回退路径将在下一步实时检查

        if L is None or not demand_ok or not semantic_ok:
            return self._demand_guided_fallback(rho_demand_voted, t_now, context, affect, eta_affect, eta_collision)

        # 6. 软因子计算（常规流程：η_collision = 1.0，不影响软因子链幅值）
        q_L = self.stm.forward(L)
        eta_cmd = 1.0 - 0.1 * self.stm.information_entropy(q_L, self.lmem.all_embeddings())
        eta_interp = sigmoid(-self._semantic_traj_distance(q_L) / self.stm.temp)
        eta_topo = self.mctm.query(context.pose)

        # 7. 构建 v6 风格上下文 + 软因子
        s_emo = self.famk.observe(context.face, t_now)
        gamma = self.famk.gamma(s_emo)
        m_topk = self.lmem.retrieve_by_semantic(q_L, k=4)
        t_topo = self.mctm.token(context.pose)
        c = build_ctx(context, s_emo, m_topk, t_topo, q_L)
        cands = self.fmpp.propose(c, K=self.fmpp.K)

        # 8. 软因子滤波（6 项链 + η_collision=1.0 占位）
        surv = []
        for x in cands:
            if not self.ggc.filter(x):
                continue
            eta_g = self.ggc.quality_factor(x)
            # η_collision 在常规流程中置 1.0；回退路径将在 _cheap_gates 中实时检查
            eta_total = eta_g * eta_topo * eta_interp * eta_cmd * eta_demand_total * eta_affect * 1.0
            if self._cheap_gates(x, gamma, eta_total):
                surv.append((x, eta_total))

        if not surv:
            return self._demand_guided_fallback(rho_demand_voted, t_now, context, affect, eta_affect, eta_collision)

        # 9. 级联筛选（VACK → BCK）
        surv.sort(key=lambda x_e: x_e[1], reverse=True)
        finals = []
        for x, _ in surv[:3]:
            vac = self.v6.vack.evaluate(x, context_with(s_emo), t_now)
            if self.v6.vack.kc_val(vac, tau=gamma['val'] * TAU_VAL5):
                if self.v6._bck_preview(x, gamma):
                    finals.append(x)

        if not finals:
            return self._demand_guided_fallback(rho_demand_voted, t_now, context, affect, eta_affect, eta_collision)

        best = max(finals, key=lambda x: self._margin(x))
        return True, best, 'FORGED_CGE_V7'

    def _demand_guided_fallback(self, rho_demand, t_now, context, affect, eta_affect, eta_collision):
        """需求导向回退：从需求检索生成行为"""
        if rho_demand is None:
            return self.v6.select(None, t_now, context)

        q_demand = self.dim.encoder(rho_demand)
        m_demand = self.lmem.retrieve_by_semantic(q_demand, k=4)
        t_topo = self.mctm.token(context.pose)
        c_demand = (context.obj, context.geo, context.theta_fp, context.task,
                    self.famk.observe(context.face, t_now), m_demand, context.rho_target, t_topo, q_demand)
        cands = self.fmpp.propose(c_demand, K=self.fmpp.K)
        # 同样软因子滤波，但 η_demand = 1.0（需求驱动默认通过）
        # 关键新增：实时碰撞检查 η_collision
        surviving = []
        for x in cands:
            if not self.ggc.filter(x):
                continue
            # 实时碰撞检测：计算 η_collision
            eta_collision_real = self._calc_collision_factor(x)  # [0,1]
            if eta_collision_real < self.tau_collision:
                continue  # 有碰撞风险，丢弃
            eta_affect_val = self.dac.get_affect_factor(affect)
            surviving.append(x)
        if not surviving:
            return False, None, 'DEMAND_FALLBACK_FAILED'
        # 按软因子排序取最佳
        surviving.sort(key=lambda x: self._margin(x), reverse=True)
        return True, surviving[0], 'DEMAND_GUIDED_FALLBACK'

    def _calc_collision_factor(self, x: Trajectory) -> float:
        """基于 GGC 碰撞网格计算 η_collision = 1 - (碰撞体素 / 总体素)"""
        collision_voxels = self.ggc.count_collision_voxels(x)
        total_voxels = self.ggc.total_voxels_in_path(x)
        if total_voxels == 0:
            return 1.0
        return 1.0 - (collision_voxels / total_voxels)

    def ecs_v7(self, x: Trajectory, n_flow: float, s_emo: SHomo | None, eta_factors: dict) -> float:
        """软评分 ECS_v7 = ECS_v6 · η_g · η_topo · η_interp · η_cmd · η_demand · η_affect · η_collision"""
        base = self.v6.ecs_v6(x, n_flow, s_emo, eta_factors)
        return base * eta_factors.get('collision', 1.0)
```

## 4. 正确性论证（增量更新）

### 定理 11（需求一致性单调性）

**陈述**：EFA-v7 软因子链 η_j ∈ [1, 1+ε]，其中 ε=0.3 设计上限。设七硬门阈值 τ_i^v7 = γ_i·τ_i^v6·Π_factor_i，其中 Π_factor_i = ∏_{j=1}^7 η_j ∈ [1, 1.3]（已包含 η_collision，常规流程中 η_collision=1.0，不计入 Π_factor_i 的幅值扩张）。则：
- Exec_CADVS-v7 ⊆ Exec_CADVS-v6（软因子只收紧）
- 若 η_demand < τ_demand，系统必走需求导向回退路径，形成「需求-行为」的可解释闭环
- 若 η_semantic < τ_semantic，系统强制语义一致性回退，不进入常规 EFA-v6 流程

**证明**：η_j ≥ 1 ⇒ Π_factor_i ≥ 1 ⇒ τ_i^v7 ≥ τ_i^v6；软阈值单调升；七硬门判定 1[s_i ≥ τ] = 1[s_i ≥ τ'] 当 τ' ≥ τ 时结果不变或更严格。若 η_demand < τ_demand，需求导向回退保证执行 x_demand，该路径的硬门判定独立于 STM。若 η_semantic < τ_semantic，语义一致性回退路径通过语义地图检索确保 ρ_demand 与检索目标的语义相近，从而避免「语义漂移」导致的错误执行。

### 定理 13（双轨需求一致性）

**陈述**：设主路径 ρ_demand^main 与备路径 ρ_demand^alt 通过投票机制选出 ρ_demand^voted，则：
- 若 sim(ρ_demand^main, ρ_demand^alt) > τ_vote，则 ρ_demand^voted = ρ_demand^main，η_demand 使用 η_demand^main，表明用户需求稳定，主路径可信
- 若 sim(ρ_demand^main, ρ_demand^alt) ≤ τ_vote，则 ρ_demand^voted = ρ_demand^alt，η_demand 使用 η_demand^alt，并标记「需求不稳定」，系统进入保守模式，优先检查 η_semantic 与 η_collision

**证明**：当主备语义相近时，历史积累有效，主路径可信；当主备语义相近度低时，说明用户需求近期发生变化或历史噪声大，备路径提供了备选视角。投票机制确保 η_demand 的使用始终对应当前被认为最可信的需求向量，从而避免在需求不稳定时盲目执行。

### 定理 14（语义地图一致性）

**陈述**：设语义地图投射 S(ρ_demand) = q_semantic，通过 Top-k 检索得到语义相近目标集 {ρ_target_1, ..., ρ_target_k}，则：
- η_semantic = 1 - (1/k)·Σ_j sim(ρ_demand, ρ_target_j) ∈ [0,1]
- 若 η_semantic ≥ τ_semantic（默认 0.6），则 ρ_demand 与可达任务的语义一致性通过，x_demand 在指令-轨迹空间中具有有效语义支撑
- 若 η_semantic < τ_semantic，系统执行语义一致性回退，检索更典型的历史任务，避免语义漂移导致的错误执行

**证明**：η_semantic 基于余弦相似度的均值，若高于阈值，表明 ρ_demand 位于任务语义簇的中心区域，可达性得到保证；若低于阈值，表明当前需求向量偏离了已知任务语义区域，强制回退机制确保了 fail-closed 边界的严格性。

### 诚实声明

- DIM 的「需求意图」是高度抽象的，存在「稀释」风险：过多历史会模糊当下需求； dual-track 通过 sim 投票缓解，但τ_vote 的设置需经验性调参
- DRC 的 LLM 推理链可能产生「幻觉」，η_demand 低于阈值时才触发回退，但误判成本仍存在；链一致性检查（定理 13）提供了额外防护
- DAC 的面部表情捕获受光照、相机分辨率影响，desire_affect 的离散化 {-1,0,+1} 可能过粗；η_affect_confidence_mod 引入置信度加权，缓解部分个体差异
- 软因子链的乘积放大误差：若所有 η_j = 0.9（误判），Π_factor_i ≈ 0.54（含 η_collision=1.0 置位），导致阈值下降、执行集扩张，破坏 fail-closed 假设。**缓解**：所有 η_j ≥ 1 设计（η_collision 除外，常规流程中置 1.0），Π_factor_i ≤ 1.3 设计上限；若检测到 η_j < 1，则立即切换至 v6 规则提议（回退策略）；η_semantic 和 η_collision 作为二级守卫，在主软因子通过时仍可拒绝有风险的提议

## 7. 本轮最大风险（最终确认）

**一句话**：**需求意图的非线性突变与自我否定**：尽管引入 dual-track DIM（通过 sim(·,·) 投票机制检测需求稳定性）、语义地图（通过 η_semantic 提供结构化一致性验证）以及碰撞软因子 η_collision（通过 GGC 实时几何守卫），但用户意图仍可能在短期内发生非线性突变或自我否定（如 suddenly switching from「放置到桌子」到「拿走到柜子」）。此时 dual-track 可能因历史权重滞后而未及时切换至备路径，语义地图的固定语义簿可能无法及时捕获全新任务，η_collision 的 GGC 网格精度有限可能漏报细小碰撞风险。这些结构上的捕获难题在维持七硬门 fail-closed 边界时，仍可能导致「正确但时机不当」、「正确但错误目标」或「有碰撞风险」的行动。

**关键防护链**：dual-track 投票 → 语义一致性检查（η_semantic） → 碰撞守卫（η_collision） → 需求导向回退兜底。三层 guard 共同作用，将单一失败点的风险降级为多点联合失败，在七硬门约束下仍难以完全根除，但概率被大幅压降。
