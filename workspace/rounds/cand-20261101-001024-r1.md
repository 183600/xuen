# 第 13 轮 · BCG：把「灵巧操作」从多指手改写为双臂接触图

> 检索/复核日期：**2026-11-01（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1（Dex1-1 夹爪），32 项桌面任务，通才单模型，选手自部署 + 官方远程真机 API。本轮是灵感循环第 1 轮，三个词是「多模态融合」「灵巧操作」「三维感知」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO；先修正三处事实，再把「灵巧」从手指改写为双臂接触，把「三维感知」从绝对深度改写为接触坐标系里的相对位姿。

## 0. 先给结论：本届的「灵巧」不是手指，是双臂接触

三句话：

1. **Dex1-1 是 1-DoF 平行夹爪，不是多指灵巧手。** 官方产品页写的是 Gripper：90 mm 行程、80 mm 爪长、5–120 N 夹持力、0.1 mm 指尖分辨率、0.24 s 全行程闭合；线上 API 每只手只给 1 个夹爪标量。把它当多指手做手指级灵巧操作，方向就错了。
2. **32 个任务里，至少 14 个评分点明确或隐含要求「一手固定/扶持，另一手操作」。** 例如拔网线要「先夹住网口，再夹住网线」，插插头要「抓住插排，再抓住插头」，收拾书包要「抓文具盒、抓书包、放入、拉链」，拉拉链要「摆正收纳包、拉上拉链」，开锁要「抓起锁、拧钥匙、拨铁环」。这不是单臂 pick-and-place 的变体，是**双臂接触丰富操作**。
3. **头双目在 0.5–1 m 的深度误差是 15–61 mm/视差像素，单靠它补不了最后 3 cm。** 但 32 个数据集的腕部彩色内参现在都在 `meta/info.json` 里；缺的是腕部外参和接触尺度的标定。正确做法不是追求全场绝对深度，而是用双目+腕部+本体做**接触坐标系里的相对位姿**，再用 5 步闭环修正。

所以本轮的押注是 **BCG（Bimanual Contact Graph，双臂接触图）**：

> 把四路 RGB、双目几何、43 维本体、语言指令和 94 个评分步骤，融合成一张 30 Hz 的米制接触图；在图上显式分配「哪只手做 fixture、哪只手做 active」，从 33k 条成功演示里检索接触模式，把 VLA 的双臂 chunk 投影到接触约束流形上，再用 5 步闭环补最后 3 cm。

一句话：**不要再问“用哪个更大的 VLA”，先问“哪只手该固定什么、另一只手该沿哪个约束运动”。**

### 1.4 Dex1-1：1-DoF 夹爪，API 只给 1 个标量

- 产品页：Gripper；行程 90 mm；爪长 80 mm；夹持力 5–120 N；指尖位置分辨率 0.1 mm；全行程最短闭合 0.24 s；通信 6 Mbps、控制 1000 Hz。
- 数据里 `action.gripper_controls` 是 4 维（trigger/squeeze），线上 API 只有 `action.left_gripper` / `action.right_gripper` 各 1 维。**数据与接口的夹爪语义不一致，必须 G0 标定。**
- 抽查多个任务：`action.*_gripper` 最大 4.5，`observation.state.*_gripper` 最大约 4.69；数据集 README 写 5.5→0.0 open→close。至少三种尺度，不能硬编码。
- 抽查 5 个双臂任务的首集：左右臂末端路径 0.81–1.93 m，两个夹爪都在动；不是“一只手完全不动”的伪双臂。

**含义**：本届的“灵巧”是 **1-DoF 夹爪 + 双臂 + 腕部 + 环境约束 + 重抓/换手**。手指级操作、手内旋转、多指抓取都不是这届的主线。

### 1.5 API：四路 RGB、43 维本体、21 维 EE 动作、chunk 内开环

- 观测：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB 480×640；`left_arm[7]`、`right_arm[7]`、`left_ee_pose[6]`、`right_ee_pose[6]`、`left_gripper[1]`、`right_gripper[1]`、`lower_body[15]`、`language`。合计 **43 维**数值状态。
- 动作：`joint` 模式 23 维（7+7+1+1+7）；`ee` 模式 **21 维**（6+6+1+1+7）。`pivot[7]` 是 lower-body/pivot target，具体 7 维映射仍需 G0。
- `action_chunk_size` 是**每个提交自己在 metadata 里声明的固定值**，不是 evaluator 强制的 30；chunk 内没有新观测，index 0 先执行，直到 evaluator 再次调用 `get_action`。
- **没有 depth、camera_info、force/torque、tactile**。夹爪是否夹住只能靠 `gripper` 状态、图像和动作历史推断。
- 每次 `get_action` 必须带 `meta.token`；N 台机器人从 8765 起连续端口；每端口 `reset()` 状态隔离。
- 另有**不计分单任务测试通道**，是做 A/B 的唯一安全场所。

**含义**：chunk size 是控制参数。要把反馈周期从 1 s 降到 167 ms，就把 `action_chunk_size` 设成 5；VLA 内部仍可预测 30 步，只返回前 5 步。这样既保留长程意图，又每 5 步重新看图。

### 1.6 官方基座：WLA 6B 已经把“大模型”做完了

- UnifoLM-WLA-1.0：6B、约 2,500 h 真机数据、64 个任务、`chunk_size=30`、`target_fps=30`、54D action/60D state；冻结 VLM，只训 DiT action head + state projector；单张 24 GB GPU 可微调；提供模型服务器。
- 挑战赛 `ee` 动作 21D，WLA 是 54D 相对 EE 动作；需要写 **54D→21D adapter**：左右 EE 6+6、gripper 1+1、pivot 7。
- WLA 的 EE 动作是相对当前 EE 系；挑战赛 `ee` 是 base 系绝对位姿。adapter 必须先 compose，再转 xyz+rpy。
- WLA 是否覆盖挑战赛 32 个任务、`pivot` 7 维如何映射、模型服务器是否接受四路图，都必须 G0 实测，不能假设。

**战略结论**：不要再从零训 6B/14B。把 WLA 当唯一学习基座，省下的算力投到**双臂角色、接触约束、最后 3 cm 闭环**。

## 2. 诊断：单臂 VLA 在这 14 个任务上为什么会输

把失败链拆开，不是“模型不够大”，而是五个具体断点：

1. **fixture 漂移**：VLA 把两只手都当 active，没人负责把插排/网口/书包/收纳包固定住。接触力一上来，fixture 被推走，active 手的相对目标就错了。
2. **角色歧义**：语言只说“拔网线”，没说“哪只手固定、哪只手拔”。单模型在 32 个任务上共享参数，很容易学到“两只手都去抓目标”的捷径。
3. **接触模式错配**：同一个“抓”在 HOLD、PIN、PULL、INSERT、ZIP、TWIST 里约束完全不同。VLA 的 RGB token 里没有显式的“现在进入 ZIP 模式，要保持 pouch 固定、沿拉链线运动”。
4. **遮挡与干扰**：腕部相机在接触段经常被物体/另一只手挡住；头双目在 0.5–1 m 只有 15–61 mm/px 的深度。没有跨视角一致性，模型会把遮挡当成物体消失。
5. **开环 chunk**：30 步 = 1 s 开环；最后 3 cm 的接触、插入、挂杯、拉拉链恰好发生在 chunk 末尾。没有 5 步闭环，错误无法在接触前修正。

**所以 BCG 不是“再加一个模块”，而是把 VLA 缺失的五个东西显式补上：fixture 角色、接触模式、约束流形、跨视角置信、5 步闭环。**

## 3. BCG：五层结构

```
四路 RGB ─┐
双目几何 ─┤
43 维本体 ─┼─> L1 米制接触图 ──> L3 角色分配 ──> L4 约束投影 + 5 步闭环 ──> 21D action
语言/评分 ─┘         ↑                 ↑                    ↑
                 L0 评分步骤图     L2 接触模式库        L5 跨视角监控/恢复
```

### 3.1 L0：评分步骤图（Score Graph）

把 94 个评分点解析成谓词 DAG，例如：

```
T05: hold(port) -> grasp(cable) -> unplug(cable, port)
T10: grasp(strip) -> grasp(plug) -> insert(plug, socket1)
T18: grasp(case) -> grasp(bag) -> put(case, bag) -> zip(bag)
T31: open_zip(case) -> put(stationery, case) -> close_zip(case)
```

用途：

- 给 VLA 的子目标提示（“现在做 hold(port)，不是抓杯子”）；
- 给 L5 做步骤完成/失败判定；
- 给恢复策略选择重试点；
- 给竞赛策略做部分分保护。

注意：这是我们对 evaluator 的近似，不是官方评分函数；只用于进度和恢复，不用于“刷分”。

### 3.2 L1：米制接触图（Metric Contact Graph）

图 `G_t = (V, E, X, A)`：

- 节点 `V`：左手、右手、任务物体、容器/固定器、桌面平面、人（若出现）。
- 边 `E`：`near`、`grasp`、`support`、`contain`、`align`、`contact`。
- 属性 `X`：base 系位姿、尺寸、可见性、置信度、语义标签、当前角色。
- 属性 `A`：接触模式、约束帧、法向、切线、允许的运动自由度。

更新：

- 头双目：校正后三角化，得到米制点云；
- 腕部：单目 + 已知夹爪开口尺度（JAW-CALIPER）或手眼标定；
- 多视角关联：用 VLA encoder token + 颜色/边缘/已知几何做关联，不用在线第二个学习分割模型；
- 时序滤波：EMA/Kalman，接触段用更高过程噪声；
- 置信度：重投影误差、双目一致性、腕部尺度、语言匹配。

### 3.3 L2：接触模式库（CM-LIB）

从 33k 成功演示中挖掘 10 种模式，每种模式带角色、约束、接近方向、柔顺性、成功谓词和失败模式：

| 模式 | 典型任务 | 约束 | 失败模式 |
|---|---|---|---|
| HOLD | T10 插插头、T18 装书包 | fixture 位姿锁定 | fixture 被推走 |
| BRACE | T14 倒药、T32 注水 | 物体压向桌面/杯口 | 打滑、倾倒 |
| PIN | T19 拉拉链、T31 文具袋 | 柔性物固定，拉链线约束 | 布料卷入、拉链卡住 |
| PULL | T05 拔网线、T23 球拍套 | 沿轴线拉，避免侧向 | 拉脱、网口移动 |
| INSERT | T10/T26 插头/网线 | 轴对齐 + 侧向柔顺 | 卡住、斜插 |
| ZIP | T18/T19/T23/T31 | 沿拉链线，保持法向 | 拉链头脱轨 |
| TWIST | T12 开锁、T14 拧盖 | 绕轴旋转，保持同轴 | 打滑、锁体转动 |
| POUR | T14 倒药、T32 注水 | 绕壶嘴/瓶口旋转，稳定容器 | 洒出、杯倒 |
| HANDOVER | 换手重抓 | 两阶段抓取 | 掉落 |
| REGRASP | 抓取失败/姿态差 | 松手、重定位、再抓 | 重复失败 |

挖掘方法：

- 用夹爪开合和 EE 运动分割演示段；
- 用评分点文本给段打弱标签；
- 对相对轨迹聚类，得到每类模式的约束参数；
- 建检索索引：输入当前图 + 子目标，检索最近邻模式/轨迹先验。

### 3.4 L3：角色分配（Role Allocator）

每个 5 步边界重新分配一次，枚举三种：

1. 左 fixture / 右 active；
2. 右 fixture / 左 active；
3. 单臂 active / 另一手 brace 或让开。

评分：

```
S(role) = w_l * language_prior
        + w_d * demo_prior
        + w_g * geometry_reachability
        + w_v * wrist_visibility
        + w_c * current_grasp
        - w_x * collision_risk
```

约束：

- 语言里出现“抓住/夹住/按住/扶住 X”时，X 附近的手优先做 fixture；
- 演示里同类任务哪只手固定，给强先验；
- 腕部相机能看到接触点的手优先做 active（否则无法伺服）；
- 已有抓取不轻易释放，除非 REGRASP 的预期收益大于风险；
- 加迟滞，避免每 5 步 flip-flop。

输出：`role_L`、`role_R`、`contact_mode`、`constraint_frame`。

### 3.5 L4：约束投影 + 5 步闭环

VLA 仍输出 30 步 chunk；我们只返回前 5 步（`action_chunk_size=5`），每 5 步重新看图。对 5 步动作做约束投影：

```
min_a  ||a - a_vla||^2_W
s.t.   A a = b        (等式：轴对齐、保持 fixture 位姿)
       C a <= d       (不等式：关节限位、碰撞、速度)
```

- HOLD：fixture 手的目标位姿锁在 `T_fixture(0)` 的容差内；active 手自由。
- INSERT：工具轴与插座轴对齐；侧向柔顺；轴向按视觉进度推进。
- ZIP：pouch 固定点锁定；拉链头沿拉链线 `l` 运动；保持法向压力。
- TWIST：锁体/瓶身固定；钥匙/瓶盖绕轴旋转 `R(t)=R(0)Exp(θe_z)`。
- POUR：瓶身绕壶嘴旋转；另一只手稳定杯口。

相对位姿是关键：

```
T_active_target = T_fixture * T_rel_target
```

`T_rel_target` 来自演示检索/评分图，不是绝对深度。这样即使 base 漂移、物体被移动，只要 fixture 手还固定着，active 手的相对目标仍然有效。最后 3 cm 再用腕部/头部视觉伺服修正；目标是一张相对目标图/相对位姿，不是“全场 3D 重建”。

### 3.6 L5：跨视角监控与恢复

- **重投影一致性**：把接触图的 3D 点投到四路图，检查光度/边缘/极线一致性；某一路残差大就降权。
- **步骤谓词**：`grasped`、`holding`、`inserted`、`zipped`、`poured`、`stacked` 等；完成/失败/超时。
- **恢复**：重定位、换接触模式、换手、REGRASP、退回上一个已完成步骤；不整集 reset。
- **人为干扰**：检测到新手/物体移动，暂停 active 手，更新图，重新分配角色；安全优先。
- **部分分保护**：最后一步风险高时，先确保前 1–2 步稳定完成；但成功率优先，不能本末倒置。

### 3.7 与第 10/11/12 轮的关系

- **FACT-VLA（第 10 轮）**：保留语言契约；BCG 把它扩展成 94 个评分步骤的谓词图。
- **GEO-RESIDUAL（第 11 轮）**：保留 3D 残差/接触思想；BCG 把残差变成图上的边和约束。
- **CHUNK-SERVO（第 12 轮）**：保留 30 步规划 + 5 步执行 + 演示检索 + 数字孪生标定；BCG 把“单臂伺服”升级为“双臂角色 + 接触约束”。
- **JOLT 候选**：它的 object map 是 BCG 的 L1 子集；BCG 新增 L2 接触模式、L3 角色分配、L4 约束投影，差异足够大。

## 4. 多模态融合与三维感知：只做“接触尺度”的融合

### 4.1 深度误差预算：头双目不够，腕部补接触尺度

头双目：

```
Z = f B / d,   σ_Z = Z^2 / (f B) * σ_d
f = 282.37 px, B = 0.0582526 m  =>  fB = 16.45 m·px
Z=0.5 m: 15.2 mm / px
Z=1.0 m: 60.8 mm / px
σ_d=0.1 px: 1.5 mm @0.5 m, 6.1 mm @1 m
```

结论：头双目适合“物体在哪、大概多大”，不适合“最后 3 cm 的插入深度”。最后 3 cm 用相对位姿 + 腕部视觉伺服，不用绝对深度。

### 4.2 JAW-CALIPER：把夹爪开口当已知尺

腕部单目看夹爪两片爪；夹爪开口 `w` 已知（0–90 mm，0.1 mm 分辨率）。若两片爪内缘在图像上相距 `Δu` 像素：

```
Z = f_x * w / Δu
σ_Z/Z = σ_w/w + σ_Δu/Δu
```

`w=90 mm, Δu=100 px, σ_Δu=0.5 px, σ_w=1 mm` → 约 1.6%；`Z=0.2 m` 时约 3.2 mm。足够做抓取宽度选择、插入深度、接触距离，不追求全场深度。

如果夹爪不可见，退化为：

- 用已知物体宽度（从演示/任务先验）；
- 用头双目 + 手眼外参；
- 用图像空间 IBVS，不做米制深度。

G0 必须先验证腕部画面里夹爪是否可见；不可见就杀。

### 4.3 可靠性融合：四路图不是简单 concat

每个视角给一个置信度 `c_v`：双目一致性、重投影误差、模糊/遮挡、语言匹配、接触可见性。融合位姿用加权最小二乘/协方差交叉：

```
x = (Σ c_v Σ_v^{-1} x_v) / (Σ c_v Σ_v^{-1})
```

被手/物体挡住的腕部图降权；头双目在接触段降权；本体 proprio 在遮挡时升权。训练时（P1）做 modality dropout，让 VLA 不依赖单一视角。

### 4.4 几何 token（P1，可选）

如果 P0 的确定性图不够，再把图节点/边编码成稀疏几何 token：

```
g_i = MLP([pose, size, confidence, semantic_embedding])
```

通过 cross-attention 注入 WLA 的 action expert；冻结 VLM，只训 adapter + action head；辅助损失：位姿/接触/可见性。它仍是**同一个模型**，不是第二个策略。ExStereo/MolmoAct2 证明这条路可行，但会增加延迟和工程量，所以放 P1，不挡 P0。

### 4.5 不做什么

- 不做全场稠密深度/NeRF/3DGS 重建；最后 3 cm 不需要。
- 不训第二个学习策略/残差网络；单模型规则下风险高。
- 不在线加载独立分割模型（SAM/GroundingDINO）；离线打标签可以，在线只用 VLA encoder + 经典几何。
- 不把世界模型当主策略；榜单头部仍是 VLA，WLA 已够大。
- 不假设预览榜单的任务排名是难度表。

## 5. 创新点清单（动机 / 差异 / 可行性 / 资源 / 步骤 / 风险）

### 5.1 BCG：双臂接触图与角色分配（P0，主押注）

- **动机**：14/32 任务需要“一手固定、一手操作”；单臂 VLA 没有显式 fixture 角色，接触力一上来夹具就漂。
- **与现有方案的差异**：头部 VLA 联合输出双臂，但没有显式角色/约束；BCG 把“谁固定、谁操作、沿什么约束”变成可检查的图结构。与第 12 轮 CHUNK-SERVO 相比，从单臂伺服升级为双臂接触约束。
- **技术可行性**：高。33k 演示含双臂/夹爪/EE 轨迹；评分点提供子目标；图/角色分配是确定性算法，不需要新数据。
- **所需资源**：1–2 名工程师；CPU 图更新；1×24GB GPU 跑 WLA；6 个双臂任务做 A/B；单任务通道。
- **落地步骤**：① 解析 94 个评分点为谓词 DAG；② 从演示挖角色标签；③ 实现 L1 图 + L3 分配；④ 在 6 个任务上做离线回放；⑤ 单任务通道 A/B；⑥ 全量 dry run。
- **风险**：角色标签噪声；图误差；约束投影与 VLA 冲突；接触段无 force 时约束可能不够。**Kill**：6 个任务平均成功率 < baseline +3pp，或角色准确率 <60%。

### 5.2 CM-LIB：从 33k 演示挖接触模式库（P0）

- **动机**：同一个“抓”在 HOLD/PIN/PULL/INSERT/ZIP/TWIST 里约束完全不同；VLA 的 RGB token 没有显式模式。
- **差异**：不是检索一条轨迹，而是检索**模式 + 约束参数 + 角色先验**；可解释、可复用、可检查。
- **可行性**：高。夹爪开合 + EE 运动可自动分段；评分点文本可弱标注；33k 演示足够覆盖 10 种模式。
- **资源**：离线 CPU/1×GPU；1 TB 存储；1 名工程师 2 周。
- **步骤**：分段 → 弱标注 → 聚类 → 拟合约束 → 建索引 → 在线检索。
- **风险**：模式边界模糊；演示噪声；新模式覆盖不足。**Kill**：14 个任务中 <8 个能匹配到稳定模式。

### 5.3 SCORE-GRAPH：94 个评分步骤 → 子目标状态机（P0）

- **动机**：步骤分是 tie-break；失败后整集 reset 会丢掉已得步骤分；恢复需要知道“现在做到哪一步”。
- **差异**：把评分文本变成可执行谓词 DAG，而不是只把任务名塞给 VLA；支持部分分保护和重试。
- **可行性**：高。32 个 `info.json` 已拿到；94 个步骤可人工/半自动解析；谓词用图像/夹爪/位姿近似。
- **资源**：1 名工程师 1 周；无需训练。
- **步骤**：解析 → 人工校对 → 谓词实现 → 回放验证 → 接入 L5。
- **风险**：谓词与官方 evaluator 不一致；误判导致错误恢复。**Kill**：回放中步骤判定准确率 <80%。

### 5.4 JAW-CALIPER：腕部夹爪卡尺（P1）

- **动机**：腕部单目没有深度；头双目在 0.5–1 m 误差 15–61 mm/px；最后 3 cm 需要接触尺度。
- **差异**：用机器人自己的夹爪开口当已知尺，不需要额外标定板/编码器；是“可变基线单目”。
- **可行性**：中高。依赖夹爪在腕部画面可见；内参已有；开口已知。
- **资源**：离线标定 1 周；1 名工程师；无需新数据。
- **步骤**：G0 检查可见性 → 爪边缘检测 → 手眼/尺度标定 → 与头双目/已知物体尺寸对比 → 接入抓取/插入。
- **风险**：夹爪被物体挡住；爪宽命令≠实际；反光。**Kill**：可见帧 <30%，或尺度误差 >10%。

### 5.5 GEOM-FUSE：可靠性融合 + 几何 token（P1/P2）

- **动机**：四路图有冗余；遮挡/人为干扰/背景变化时，固定 concat 会崩；ExStereo/MolmoAct2 证明几何 token 有效。
- **差异**：不是稠密深度，而是**稀疏对象/接触 token + 可靠性权重**；比全量 stereo 分支便宜。
- **可行性**：中。需要改 WLA action expert 的 cross-attention；24GB 可训 adapter；但工程量大。
- **资源**：1×24GB GPU；2–4 GPU 周；1–2 名工程师。
- **步骤**：离线几何 token → adapter + cross-attention → 辅助损失 → 消融 → 单任务 A/B。
- **风险**：几何噪声；延迟；可能不如确定性图；单模型合规需确认。**Kill**：6 个任务上不如 BCG-only，或延迟超预算。

### 5.6 XV-MONITOR：跨视角一致性监控（P1）

- **动机**：接触段腕部遮挡、头双目误差大；需要知道“哪一路现在不可信”。
- **差异**：用重投影/极线/光度/语言一致性做确定性监控，不训失败检测器。
- **可行性**：高；无需训练；CPU 便宜。
- **资源**：1 名工程师 1 周。
- **步骤**：重投影 → 残差 → 阈值/降权 → 触发重定位/恢复。
- **风险**：阈值误报；反光/弱纹理。**Kill**：误报率 >10%，或对成功率无增益。

### 5.7 剪枝清单

- 不训第二个 6B/14B VLA；WLA 已够大。
- 不做多指手内操作；Dex1 是 1-DoF。
- 不做全场稠密 3D/NeRF；最后 3 cm 用相对位姿。
- 不做 per-task 策略；单模型规则。
- 不把预览榜单当难度表。
- 不在线加独立分割模型；离线标签可以。
- 不为了步骤分牺牲 easy 任务的成功率。

## 7. 竞赛策略

- **10 trials/task 是固定的**（32×10=320），不是可分配的投资组合；投资组合是**工程精力、提交顺序、单任务 A/B 的选择**。
- **排名**：平均成功率 > 平均步骤分 > 更早提交。先交一个安全基线锁 tie-break，再逐步加 BCG；不要一次上全量导致回退。
- **任务分层**：
  - A 档（BCG 主战场）：T05、T10、T16、T18、T19、T22、T23、T26、T28、T31、T32。
  - B 档（稳成功率）：T01–T04、T06、T08、T13、T15、T17、T20、T21、T25、T27。
  - C 档（难单臂/接触/动态）：T09、T11、T12、T14、T24、T29、T30；T24 是传送带动态任务，图更新要预测，本轮不作为主战场；C 档用步骤分保护，不牺牲 B 档。
- **单任务通道**：每个改动先在 6 个双臂任务上 A/B；无增益不上全量。
- **泛化**：5 类各 2 次；BCG 的可靠性融合和跨视角监控优先针对遮挡、背景、干扰物、人为干扰。
- **多端口**：N 个端口；图/控制器 per-port；VLA 可批处理；每端口 `reset()` 隔离；token 每次带。

## 8. 风险与合规

- **单模型规则**：在线学习组件必须属于同一个 checkpoint；确定性图/控制器可以。采用 C1/C2/C3：
  - C1：离线标注/挖掘可用任何工具；
  - C2：在线只用确定性几何/伺服/检索控制器，不加学习残差；
  - C3：若加几何 token，它必须和 action head 一起训练、同一模型导出，不加载第二个策略。
- **在线分割模型**：SAM/GroundingDINO 等如果在线加载，可能被认定为第二个模型；默认不用，离线打标签可以。
- **无 force/tactile**：接触段靠位置柔顺、速度限制、夹爪开合、视觉滑移检测；紧配合任务可能仍需 CHUNK-SERVO 兜底。
- **标定风险**：腕部外参、夹爪可见性、gripper 尺度、pivot 7 维映射；G0 不过就不上。
- **评分图风险**：94 个谓词是我们的近似，不是官方评分；只用于进度/恢复。
- **人为干扰/安全**：检测到人/物体突入，暂停 active 手；180 s 内不冒险。
- **数据偏差**：未见物品/背景变化；用可靠性融合和 modality dropout 缓解。
- **时间风险**：BCG 工程量大；P0 只做 L0/L1/L3/L4 的确定性版本，GEOM-FUSE 放 P1。

# 第 13 轮产物 · BCG 技术报告：双臂接触图、评分步骤状态机与最后 3 厘米闭环

> 检索/复核日期：**2026-11-01（UTC）**。本报告是第 13 轮「BCG」的工程化版本；不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO。所有外部事实带来源编号（见 §10）。本轮**没有真机实验**；§6 给出可执行实验设计、验收标准与已有离线抽查结果，明确区分“已观察”和“待验证”。

## 0. 结论与边界

### 0.1 一句话

> 本届 UniBot 的“灵巧操作”不是多指手内操作，而是 **1-DoF 平行夹爪下的双臂接触丰富操作**；最值得押注的是 **BCG**：把四路 RGB、双目几何、43 维本体、语言和 94 个评分步骤融合成一张米制接触图，显式分配 fixture/active 手，把 VLA 的双臂 chunk 投影到接触约束流形上，再用 5 步闭环补最后 3 cm。

### 0.2 它是什么

- 一个**确定性**的双臂接触图 + 角色分配 + 约束投影层；
- 一个**评分步骤状态机**，用于进度判定、恢复、部分分保护；
- 一个**5 步闭环**执行策略（`action_chunk_size=5`），VLA 内部仍可预测 30 步；
- 一个**WLA/API adapter**，把 54D 相对 EE 动作映射到挑战赛 21D 绝对 EE 动作；
- 一个**离线接触模式库**，从 33k 成功演示中挖掘 HOLD/PIN/PULL/INSERT/ZIP/TWIST/POUR 等模式。

### 0.3 它不是什么

- 不是第二个学习策略/残差网络；
- 不是多指手内操作；
- 不是全场稠密 3D/NeRF/3DGS；
- 不是从零训 6B/14B VLA；
- 不是 per-task 策略集合；
- 不是“刷步骤分”的 evaluator hack。

### 0.4 合规边界（C1/C2/C3）

- **C1 离线可以任意**：用 SAM/GroundingDINO/人工标注做离线伪标签、模式挖掘、回放，不进入提交。
- **C2 在线确定性控制器可以**：图更新、角色分配、约束投影、视觉伺服、跨视角监控都不含学习权重，不构成第二个模型。
- **C3 在线学习组件必须同模型**：若加几何 token adapter，它必须与 action head 一起训练、同一 checkpoint 导出；不得在线加载第二个策略或独立分割模型。

## 2. 问题形式化

### 2.1 观测与动作

观测：

```
o_t = ( I_t^HL, I_t^HR, I_t^WL, I_t^WR, q_t, g_t, l, token )
```

- `I`：四路 RGB 480×640；
- `q_t ∈ R^43`：左右臂 7+7、左右 EE 6+6、夹爪 1+1、lower_body 15；
- `g_t`：夹爪开合状态；
- `l`：语言指令；
- `token`：提交 token。

动作（`ee` 模式）：

```
a_t = ( p_t^L, r_t^L, p_t^R, r_t^R, u_t^L, u_t^R, π_t )
```

- `p^L, p^R ∈ R^3`：base 系位置；
- `r^L, r^R ∈ R^3`：base 系 rpy；
- `u^L, u^R ∈ R`：夹爪标量；
- `π_t ∈ R^7`：pivot/lower-body target。

chunk：

```
A_t = (a_t, a_{t+1}, ..., a_{t+T_a-1}),  T_a = action_chunk_size
```

本轮取 `T_a=5`；VLA 内部可预测 30 步，只返回前 5 步。

### 2.2 接触图

定义：

```
G_t = ( V_t, E_t, X_t, A_t )
```

- `V_t = H_L ∪ H_R ∪ O_t ∪ F_t ∪ {table} ∪ {human_t}`；
- `E_t ⊆ V_t × V_t × R`，`R = {near, grasp, support, contain, align, contact}`；
- `X_t`：每个节点的 base 系位姿 `T_v`、包围盒 `b_v`、置信度 `c_v`、语义 `s_v`；
- `A_t`：每条边的接触模式、约束帧、法向、允许运动自由度。

图的目标不是“重建整个世界”，而是回答四个问题：

1. 哪只手已经固定了什么？
2. 另一只手要相对哪个坐标系运动？
3. 当前接触模式允许哪些自由度？
4. 哪一路视角现在不可信？

### 2.3 角色分配

角色：

```
r_t = (r_L, r_R) ∈ {fixture, active, brace, free}^2
```

对每个接触模式 `m`，合法角色集合 `R(m)` 是：

- `(fixture, active)`；
- `(active, fixture)`；
- `(brace, active)` / `(active, brace)`；
- `(free, active)` / `(active, free)`。

评分：

```
S(r) = w_l L(r) + w_d D(r) + w_g G(r) + w_v V(r) + w_c C(r) - w_x X(r)
```

- `L`：语言先验（“抓住/夹住/按住/扶住 X”）；
- `D`：演示先验（同类任务哪只手固定）；
- `G`：几何可达/IK；
- `V`：腕部可见性；
- `C`：当前抓取状态；
- `X`：碰撞风险。

选择：

```
r_t^* = argmax_{r ∈ R(m)} [ S(r) - w_h * 1(r != r_{t-1}) ]
```

`w_h` 是迟滞项，防止 5 步边界 flip-flop。

### 2.4 约束投影

VLA 输出 `a_vla`；投影到约束流形：

```
a^* = argmin_a  ||a - a_vla||_W^2
      s.t.    A a = b        (等式约束)
              C a <= d       (不等式约束)
```

只有等式时闭式解：

```
a^* = a_vla - W^{-1} A^T (A W^{-1} A^T)^{-1} (A a_vla - b)
```

有不等式时用 QP/active-set；工程上可先做等式投影，再把不等式作为软惩罚。

### 2.5 步骤状态机

每个任务 `k=1..K` 个步骤，状态：

```
s_k ∈ {pending, active, done, failed}
```

转移：

- `pending -> active`：前驱完成；
- `active -> done`：谓词 `φ_k(G_t, o_t)` 为真；
- `active -> failed`：超时或 `ψ_k` 为真；
- `failed -> active`：换接触模式/换手/REGRASP 后重试。

谓词是近似，不是官方评分；只用于进度和恢复。

### 2.6 优化目标

竞赛目标：

```
maximize  (1/32) Σ_i success_i
then      (1/32) Σ_i step_score_i
then      earlier submission
```

工程目标：

```
maximize  P(Δsuccess) / cost
subject to  no regression on easy tasks
            single-model compliance
            latency budget
```

步骤分的期望：

```
E[step_score] = Σ_k w_k * Π_{j<=k} p_j
P(success) = Π_k p_k
```

这说明：早期步骤的 `p_j` 同时影响成功率和步骤分；最后一步只影响成功率。若最后一步风险高，先确保前面步骤，是合理的 tie-break 策略；但不能牺牲成功率。

## 3. 系统设计

### 3.1 总架构

```
┌──────────────────────────────────────────────────────────────────┐
│                        PolicyService (per port)                   │
│                                                                  │
│  obs ──> ObsAdapter ──> L1 Metric Graph ──> L3 Role Allocator    │
│   │         │                 ↑                    │             │
│   │         │            L0 Score Graph            │             │
│   │         │                 ↑                    ↓             │
│   │         └────────> L2 CM-LIB ──────────> L4 Constraint       │
│   │                              ↑                 Projection     │
│   │                              │                    │           │
│   └──────────────────────> L5 Cross-View Monitor <───┘           │
│                                      │                            │
│                                      ↓                            │
│                              WLA / VLA Adapter ──> 21D chunk      │
└──────────────────────────────────────────────────────────────────┘
```

数据流：

1. `ObsAdapter` 把挑战赛 4 图 + 43D 本体 + 语言转成内部格式；
2. `L1` 更新米制接触图；
3. `L0` 更新步骤状态；
4. `L3` 分配 fixture/active；
5. `L4` 调 VLA 预测 30 步，取前 5 步，投影到约束；
6. `L5` 用四路图监控一致性，失败则恢复；
7. 返回 5 步 21D action chunk。

#### 3.3.3 3D 提升

头双目（校正后）：

```
d = u_L - u_R
Z = f B / d
X = (u - c_x) Z / f
Y = (v - c_y) Z / f
```

腕部单目（JAW-CALIPER）：

```
Z = f_x w / Δu
X = (u - c_x) Z / f_x
Y = (v - c_y) Z / f_y
```

到 base：

```
T_base_cam = T_base_ee * T_ee_cam
```

`T_ee_cam` 来自手眼标定；没有时用头双目/已知几何近似。

#### 3.3.4 关联

- 特征：VLA encoder token、颜色直方图、3D 距离、尺寸；
- 匹配：Hungarian；
- 时序：EMA/Kalman；
- 置信度：重投影误差、双目一致性、腕部尺度、语言匹配；
- **不**在线加载独立分割模型；离线标签可以。

### 3.4 L2：接触模式库

#### 3.4.1 模式定义

| 模式 | 角色 | 约束 | 成功谓词 | 失败模式 |
|---|---|---|---|---|
| HOLD | 一手 fixture，一手 active | fixture 位姿锁定 | `holding(fixture)` | fixture 漂移 |
| BRACE | 一手 brace，一手 active | 物体压向桌面/杯口 | `stable(obj)` | 打滑/倾倒 |
| PIN | 一手 pin，一手 active | 柔性物固定点 | `pinned(obj)` | 布料卷入 |
| PULL | 一手 fixture，一手 active | 沿轴线拉 | `pulled(obj)` | 拉脱 |
| INSERT | 一手 fixture，一手 active | 轴对齐 + 侧向柔顺 | `inserted(obj, rec)` | 卡住/斜插 |
| ZIP | 一手 pin，一手 active | 沿拉链线 | `zipped(zip)` | 拉链头脱轨 |
| TWIST | 一手 fixture，一手 active | 绕轴旋转 | `turned(cap)` | 打滑 |
| POUR | 一手 fixture，一手 active | 绕壶嘴旋转 | `poured(src, dst)` | 洒出 |
| HANDOVER | 双手 | 两阶段抓取 | `holding(other_hand)` | 掉落 |
| REGRASP | 单/双手 | 松手重定位 | `grasped(obj)` | 重复失败 |

#### 3.4.2 挖掘流程

1. **分段**：夹爪闭合/打开事件 + EE 速度阈值；
2. **弱标注**：评分点文本映射到模式；
3. **聚类**：相对轨迹 DTW/k-means；
4. **拟合**：约束帧、接近方向、柔顺参数；
5. **索引**：`(task, subgoal, object_class, relative_pose, gripper_width)`；
6. **检索**：最近邻返回模式 + 轨迹先验。

#### 3.4.3 角色标签

从演示自动推断：

- `fixture`：夹爪闭合 + EE 位置稳定 + 另一只手在动；
- `active`：夹爪闭合/开合 + EE 明显运动；
- `brace`：夹爪闭合 + 物体压向支撑面；
- `free`：夹爪打开 + EE 稳定。

用 HMM 平滑；人工抽检 100 个 episode 估计准确率。

### 3.5 L3：角色分配

#### 3.5.1 特征

| 特征 | 计算 | 权重 |
|---|---|---|
| `L` | 语言中的 hold/grasp/brace 对象与手的距离 | `w_l` |
| `D` | CM-LIB 检索到的同类 episode 的角色频率 | `w_d` |
| `G` | IK 可达 + 关节限位 + 碰撞 | `w_g` |
| `V` | 腕部相机是否能看到接触点 | `w_v` |
| `C` | 当前夹爪开合/已抓取 | `w_c` |
| `X` | 碰撞/自碰撞/桌面碰撞 | `-w_x` |

#### 3.5.2 枚举

```
for r in valid_roles(m):
    score = w_l*L(r) + w_d*D(r) + w_g*G(r) + w_v*V(r) + w_c*C(r) - w_x*X(r)
    score -= w_h * (r != r_prev)
choose argmax
```

#### 3.5.3 迟滞/换手

- 每 5 步重评一次；
- 若当前 active 手的腕部被挡，且另一只手可见，考虑 HANDOVER；
- 若 fixture 手打滑，先 REGRASP，不要继续 active；
- 若双手都需要做 active，优先完成评分图中更早的步骤。

### 3.6 L4：约束投影 + 5 步闭环

#### 3.6.1 约束表

| 模式 | 等式约束 | 不等式约束 | 控制 |
|---|---|---|---|
| HOLD | `T_fixture = T_fixture(0)` | `||Δp||<ε_p`, `||Δr||<ε_r` | fixture 保持，active 自由 |
| INSERT | 工具轴 = 插座轴 | 侧向偏差 <ε_lat | 轴向推进 + 侧向柔顺 |
| ZIP | 拉链头在拉链线 `l` 上 | 法向力/速度 | 沿线运动 |
| TWIST | 旋转轴 = 钥匙/瓶盖轴 | 力矩/速度 | 绕轴旋转 |
| POUR | 瓶口在杯口上方 | 倾斜角/流速 | 绕壶嘴旋转 |
| PULL | 拉力沿轴线 | 侧向力 <ε | 轴向拉 |

#### 3.6.2 投影

```
a* = argmin ||a - a_vla||_W^2
     s.t.  A a = b
           C a <= d
```

工程实现：

1. 先做等式投影（闭式）；
2. 再做不等式裁剪/软惩罚；
3. 若投影后与 `a_vla` 偏差 > 阈值，触发 L5 重新分配角色/模式；
4. 输出 5 步。

#### 3.6.3 相对位姿

```
T_rel = T_base_fixture^{-1} * T_base_active
T_base_active^* = T_base_fixture * T_rel^*
```

优点：

- 抵消 base 漂移；
- 抵消物体被移动的共模误差；
- 适合“一手固定、一手操作”的接触段；
- 不依赖全场绝对深度。

#### 3.6.4 最后 3 cm

- 头双目负责“物体大概在哪”；
- 腕部负责“夹爪和接触点差多少”；
- 目标是一张相对目标图/相对位姿，不是绝对 3D 点；
- 5 步闭环在接触前修正，避免 1 s 开环冲到接触。

### 3.7 L5：跨视角监控与恢复

#### 3.7.1 监控信号

| 信号 | 计算 | 触发 |
|---|---|---|
| 重投影误差 | 3D 点投到四路图 | >阈值降权 |
| 双目一致性 | 左右图匹配 | 不一致降权 |
| 腕部尺度 | JAW-CALIPER 误差 | 误差大降权 |
| 语言-物体匹配 | 语义相似度 | 不匹配重定位 |
| 接触一致性 | 夹爪开合 vs 物体距离 | 不一致恢复 |
| 时序一致性 | 位姿跳变 | 跳变重定位 |

#### 3.7.2 恢复策略

1. **重定位**：更新图，重置滤波器；
2. **换模式**：HOLD -> BRACE/PIN/REGRASP；
3. **换手**：HANDOVER；
4. **退回**：回到上一个 done 步骤；
5. **安全暂停**：检测到人/碰撞风险，暂停 active 手。

#### 3.7.3 部分分保护

- 若步骤 `k` 已 done，不因后续失败而 reset；
- 若最后一步风险高，先确保前面步骤；
- 但成功率优先，不能为了步骤分放弃成功机会。

```python
def wla_to_challenge(wla_action, obs, T_ee_cam=None):
    # 1. split WLA 54D into named components (per WLA docs)
    left_rel, right_rel, left_grip, right_grip, pivot = split_wla(wla_action)

    # 2. compose relative EE to absolute base
    T_base_ee_L = pose6_to_T(obs["left_ee_pose"])
    T_base_ee_R = pose6_to_T(obs["right_ee_pose"])
    T_base_ee_L_t = T_base_ee_L @ rel6_to_T(left_rel)
    T_base_ee_R_t = T_base_ee_R @ rel6_to_T(right_rel)

    # 3. to xyz + rpy
    left_pose = T_to_pose6(T_base_ee_L_t)
    right_pose = T_to_pose6(T_base_ee_R_t)

    # 4. gripper range calibration (G0)
    left_u = map_gripper(left_grip)
    right_u = map_gripper(right_grip)

    # 5. pivot 7D mapping (G0; default hold/zero if unknown)
    pivot7 = map_pivot(pivot, obs["lower_body"])

    return concat(left_pose, right_pose, [left_u, right_u], pivot7)
```

## 4. 推导

### 4.1 双目深度误差

```
Z = f B / d
∂Z/∂d = -f B / d^2 = -Z^2 / (f B)
σ_Z = (Z^2 / (f B)) σ_d
```

`f=282.37 px`, `B=0.0582526 m`, `fB=16.45 m·px`：

| Z | σ_Z / px | σ_Z @0.1 px |
|---:|---:|---:|
| 0.3 m | 5.5 mm | 0.55 mm |
| 0.5 m | 15.2 mm | 1.52 mm |
| 0.7 m | 29.8 mm | 2.98 mm |
| 1.0 m | 60.8 mm | 6.08 mm |

结论：头双目适合粗定位；最后 3 cm 用相对位姿/腕部视觉伺服。

### 4.2 JAW-CALIPER

```
Z = f_x w / Δu
σ_Z/Z = σ_w/w + σ_Δu/Δu
```

`w=90 mm`, `Δu=100 px`, `σ_Δu=0.5 px`, `σ_w=1 mm`：

```
σ_Z/Z = 1/90 + 0.5/100 = 0.0111 + 0.005 = 1.61%
Z=0.2 m -> 3.2 mm
```

如果 `Δu=50 px`：`σ_Z/Z=1.11%+1%=2.11%`，`Z=0.2m -> 4.2mm`。仍可接受。

标定：

1. 固定夹爪开口 `w`，拍腕部图；
2. 检测两片爪内缘 `u_L,u_R`；
3. 用已知 `w` 求 `Z`；
4. 移动已知距离，拟合 `f_x`/畸变；
5. 用头双目/已知物体尺寸交叉验证；
6. 若夹爪不可见，退回图像空间 IBVS。

### 4.3 相对位姿的漂移抵消

设 fixture 手真实位姿 `T_f`，估计 `T̂_f = T_f Δ`；active 目标 `T_a^* = T_f T_rel^*`。用估计：

```
T̂_a^* = T̂_f T_rel^* = T_f Δ T_rel^*
```

若 `Δ` 是共模漂移（base/物体整体移动），相对位姿仍保持 `T_rel^*`；若 `Δ` 是 fixture 手自身漂移，则 active 目标跟着漂移——这正是为什么 fixture 手要优先锁定/视觉伺服，而不是只靠开环。

### 4.4 约束投影

只有等式时：

```
L = (a-a_vla)^T W (a-a_vla) + λ^T (A a - b)
∂L/∂a = 2W(a-a_vla) + A^T λ = 0
a = a_vla - 0.5 W^{-1} A^T λ
A a = b -> A a_vla - 0.5 A W^{-1} A^T λ = b
λ = 2 (A W^{-1} A^T)^{-1} (A a_vla - b)
a^* = a_vla - W^{-1} A^T (A W^{-1} A^T)^{-1} (A a_vla - b)
```

不等式用 QP；工程上可用 soft penalty：

```
L = ||a-a_vla||_W^2 + ρ * ||max(0, C a - d)||^2
```

`ρ` 大 -> 更硬；但可能无解；需要 L5 检查。

### 4.5 角色分配

两个角色、两只手，最多 2 种双 role 分配 + 2 种单臂分配；枚举成本可忽略。评分函数是线性的，权重可用离线演示做逻辑回归/排序学习；但**在线不引入学习模型**，权重固定。

### 4.6 chunk size / 延迟

```
反馈周期 = T_a / 30 + τ_rtt
```

| T_a | 控制时长 | τ=50ms | τ=100ms | τ=150ms |
|---:|---:|---:|---:|---:|
| 3 | 100 ms | 150 ms | 200 ms | 250 ms |
| 5 | 167 ms | 217 ms | 267 ms | 317 ms |
| 10 | 333 ms | 383 ms | 433 ms | 483 ms |
| 30 | 1000 ms | 1050 ms | 1100 ms | 1150 ms |

选择：

- 自由空间：`T_a=10`；
- 接触/插入/拉链：`T_a=5`；
- 高动态（传送带/人为干扰）：`T_a=3`；
- 不要用 `T_a=30` 做接触段。

### 4.7 步骤分与成功率

若每步独立成功概率 `p`，K 步：

```
P(success) = p^K
E[step_score] = Σ_{k=1..K} w_k p^k
```

例：K=4，w=25，p=0.8：

```
P(success)=0.4096
E[step_score]=25*(0.8+0.64+0.512+0.4096)=59.0
```

说明：前两步贡献 36 分，是 tie-break 的主要来源；但成功率只有 41%。若把最后一步从 0.8 提到 0.9，成功率到 46.1%，步骤分到 60.3；若把第一步从 0.8 提到 0.9，成功率同样到 46.1%，步骤分到 66.4。**早期步骤的边际收益更高**，但成功率的乘积效应要求每一步都不能太差。

## 5. 伪代码

### 5.1 主循环

```python
class BCGPolicy:
    def reset(self):
        self.graph = None
        self.step_state = None
        self.role_prev = None
        self.mode = None
        self.history = []

    def get_action(self, obs):
        # 1. adapt observation
        o = self.obs_adapter(obs)

        # 2. update graph
        self.graph = update_graph(self.graph, o)

        # 3. update score step state
        self.step_state = update_step_state(
            self.graph, self.step_state, self.score_graph
        )

        # 4. select contact mode + roles
        m = select_contact_mode(self.graph, self.step_state, self.cm_lib)
        r = allocate_roles(self.graph, self.step_state, m, self.role_prev)
        self.role_prev = r
        self.mode = m

        # 5. VLA plan (30 steps internally)
        a_vla = self.vla.infer(o, subgoal=self.step_state.active_subgoal)

        # 6. project first 5 steps to contact constraints
        a_chunk = []
        for k in range(5):
            a = project_to_constraints(a_vla[k], self.graph, r, m)
            a = servo_correct(a, self.graph, r, m)
            a_chunk.append(a)

        # 7. monitor + recovery
        if not cross_view_consistent(self.graph):
            self.recover()

        return self.action_adapter(a_chunk)
```

### 5.3 角色分配

```python
def allocate_roles(G, S, mode, prev):
    best = None
    for r in valid_roles(mode):
        score = (
            w_l * language_prior(G, S, r)
            + w_d * demo_prior(G, S, r)
            + w_g * reachability(G, r)
            + w_v * wrist_visibility(G, r)
            + w_c * current_grasp(G, r)
            - w_x * collision_risk(G, r)
            - w_h * (r != prev)
        )
        if best is None or score > best.score:
            best = (r, score)
    return best[0]
```

### 5.4 约束投影

```python
def project_to_constraints(a, G, r, mode):
    A, b, C, d = build_constraints(G, r, mode)
    if A is None:
        return a
    # equality projection
    W = np.eye(len(a))
    At = A.T
    a_proj = a - W @ At @ np.linalg.solve(A @ W @ At, A @ a - b)
    # inequality soft penalty
    if C is not None:
        a_proj = soft_clip(a_proj, C, d)
    return a_proj
```

### 5.5 恢复

```python
def recover(self):
    if self.step_state.failed:
        alt = self.cm_lib.alternatives(self.mode)
        if alt:
            self.mode = alt[0]
            self.role_prev = None
        else:
            self.regrasp()
    if not cross_view_consistent(self.graph):
        self.graph = relocalize(self.graph)
```

## 6. 实验设计

### 6.1 假设

- **H1**：在 14 个双臂任务上，显式 fixture/active 角色分配比“双臂都 active”的 VLA 成功率高。
- **H2**：接触模式约束投影减少 fixture 漂移和插入斜插，提高步骤分。
- **H3**：5 步闭环比 30 步开环在接触段成功率高，但请求频率更高；存在最优 chunk size。
- **H4**：腕部内参 + JAW-CALIPER 能在最后 3 cm 提供足够尺度，优于纯头双目。
- **H5**：跨视角一致性监控能降低遮挡/人为干扰下的失败，但阈值过紧会误报。
- **H6**：SCORE-GRAPH 的步骤判定能提高恢复成功率/步骤分，但谓词误差会带来误恢复。

## 7. 竞赛策略

### 7.1 排名数学

```
S = (1/32) Σ_i s_i       # 平均成功率
P = (1/32) Σ_i p_i       # 平均步骤分
```

每个任务 10 trials，`s_i = k_i/10`；`p_i` 是该任务步骤分的平均。排名先 `S`，再 `P`，再提交时间。

工程边际收益：

```
value(change) ≈ P(ΔS) * 1/32 / cost
```

步骤分只在 `S` 打平时有价值；所以**不要为了步骤分牺牲 easy 任务的成功率**。

### 7.2 任务分层

| 档 | 任务 | 策略 |
|---|---|---|
| A（BCG 主战场） | T05、T10、T16、T18、T19、T22、T23、T26、T28、T31、T32 | 角色分配 + 接触约束 + 5 步闭环 |
| B（稳成功率） | T01–T04、T06、T08、T13、T15、T17、T20、T21、T25、T27 | 保持 baseline，不回归 |
| C（难单臂/接触） | T09、T11、T12、T14、T24、T29、T30 | 步骤分保护，CHUNK-SERVO 兜底 |

### 7.3 提交顺序

1. **安全基线**：WLA + 固定 chunk，先交，锁 tie-break；
2. **CHUNK-SERVO**：`T_a=5`，单臂 5 步闭环；验证延迟/稳定性；
3. **BCG 6 任务**：T05/T10/T18/T19/T26/T31，单任务通道 A/B；
4. **BCG 全量**：A 档 + B 档，C 档兜底；
5. **JAW-CALIPER / GEOM-FUSE**：只在有增益时上，避免回退。

### 7.4 单任务通道

- 不计分，适合 A/B；
- 每个改动先跑 6 个 A 档任务 ×10；
- 用二项分布置信区间判断，不要被 1–2 次波动骗；
- 记录失败模式，按模式修，不按任务过拟合。

### 7.5 多端口

- N 个端口，8765 起连续；
- 每端口独立 `reset()`；
- VLA 可共享/批处理；图/控制器 per-port；
- GPU 显存/吞吐估算：WLA 6B + 4 图 + 5 步 chunk；若不够，降低图像分辨率/批大小，不要加长 chunk；
- 用 Action Chunk Scheduling 的思路做请求队列，避免不同端口 chunk 速率不一致导致排队。

## 9. 风险与合规

### 9.1 合规

- **单模型**：在线只加载一个策略 checkpoint；BCG 的图/控制器是确定性代码；几何 token 若使用，必须与 action head 同模型。
- **离线工具**：SAM/GroundingDINO/人工标注只用于离线；不进入提交。
- **不混模型**：不把 MolmoAct2 + WLA + 另一个 VLA 集成；不按任务切换模型。
- **不伪造**：SCORE-GRAPH 只用于进度/恢复，不用于直接向 evaluator 报分。

### 9.2 技术风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 腕部夹爪不可见 | JAW-CALIPER 失效 | G0 检查；退回 IBVS/头双目 |
| 夹爪范围不一致 | 抓取失败/过紧 | G0 标定；用 gripper state 闭环 |
| 腕部外参缺失 | 3D 变换错 | 手眼标定；用头双目/EE 近似 |
| 接触图误差 | 角色/约束错 | 置信度/降权；只用相对位姿 |
| 无 force/tactile | 插入/拧/拉链难 | 位置柔顺、速度限制、视觉滑移 |
| 评分图谓词错 | 误恢复 | 只用步骤完成/超时；人工抽检 |
| 延迟超预算 | 5 步闭环退化 | 降图频率/分辨率；批处理 |
| 人为干扰 | 碰撞/失败 | 监控暂停；重定位；安全优先 |
| 数据偏差 | 未见物品失败 | 可靠性融合；modality dropout |
| 回退 | 排名下降 | 单任务 A/B；回退阈值 5pp |

### 9.3 伦理/安全

- 远程真机，必须避免伤人/损坏设备；
- 检测到人进入工作区，暂停 active 手；
- 不绕过 evaluator 安全限制；
- 不利用接口漏洞刷分。
