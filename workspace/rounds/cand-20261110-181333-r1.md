# 第 44 轮（新循环第 4 轮） · Cert-Lifecycle-Machine × Comparative-Cert：把证书从「布尔快照」升级为「可验证生命周期状态机」，把对比实验升级为「anytime-valid 准入证据」（四层架构 v9）

> 承接第 43 轮 v20（PCE × CCR × ICV）。v20 自陈最大风险是「共形边际覆盖被欺骗 + 多用户契约求交为空」，但它还压着两个**结构性**弱点尚未处理：**(H1) 证书被当作无历史的布尔快照**——C_u、租约 ℓ、LO/HI 模式都是「此刻是否 valid」的谓词，却没有「证书如何从候选变成有权威、又如何被降级/吊销」的合法生命周期。历史证明，静默不 sound 极少来自单点谓词写错，更多来自**非法迁移**：影子证书未攒够证据就上线、覆盖漂移时 Active 仍按时间续租、多用户协商期间旧证书继续放行。**(H2)「A/B 无回归」只是口头闸门**——v20 的认证扩张三重闸门中没有实验设计：在连续监控/提前停止下用固定 p 值会系统性放大假阳性；多 persona 反复比较造成多重比较膨胀；仿真/日志回放与在线分布不一致会让「无回归」不可迁移。本轮灵感词「状态机」「对比实验」精确命中这两个洞：**状态机**把安全命题从「谓词成立」升级为「状态机不变式 + 迁移卫兵」；**对比实验**把「扩张持证」升级为「配对、预注册、anytime-valid、控制 FWER 的因果证据」。二者耦合出本轮真正的新结构：**促权慢而贵、降权快而免费**的棘轮状态机，以及「状态决定必须做哪种对比实验、证据反过来守卫迁移」的联合协议。

## 0. 直觉与动机

**灵感 1（状态机 → 证书是「驾照」，不是「车况检查」）**：直觉上，我们从不问「这辆车此刻合不合格」，而问「谁在什么证据下有权把它从实习驾照升为正式驾照、何时必须吊销」。证书也应有生命周期：`Draft`（契约刚编译）→ `Calib`（共形校准/阈值拟合）→ `Shadow`（与现任并行跑，但**无执行权**）→ `Canary`（只在低风险子域有小额执行权）→ `Active`（按契约全权）→ `Degraded`（证据/租约将过期，退回纯收缩）→ `Suspended`（红线事件，零执行权）→ `Retired`。关键设计是 **权威阶梯 α(q)** 与 **棘轮不变式**：促权（α 上升）必须沿完整链条逐级走、每级证据等级单调不减；降权（α 下降）不要求新证据、可被**单个负事件**立即触发。这样「安全」= 任何可达状态都满足权威不超过证据，而不是寄希望于某次谓词判对。

**灵感 2（对比实验 → 扩张问题是「非劣性因果问题」，不是绝对阈值问题）**：v20 用绝对门槛回答「新策略够不够好」，但促权真正要回答的是「**新策略是否比现任更差**」。这是配对非劣性检验：同一初始状态、同一随机种子、同一场景块，候选与现任的配对差 d_i = m_cand − m_inc，原假设 H0: μ_d ≤ −δ（候选至少差 δ）。三个统计陷阱必须正面处理：**(a) 可选停止**——在线监控随时可能因「看起来没回归」而停，固定 p 值在此失效，改用 e-process/置信序列，Ville 不等式给出任意停止时刻的 Type-I 控制；**(b) 多重比较**——多 persona × 多指标反复比，FWER 会膨胀，用 e-value 合并或 Holm 校正；**(c) 迁移性**——仿真/日志回放要满足支撑条件（positivity）与有界重要性权重，否则只能作 Shadow 辅助信号，不能单独授权。一句话：**促权不是「没看到坏」，而是「以受控错误率排除了坏到 δ 以上」**。

**灵感 3（耦合 → 状态 × 证据的双向协议与多用户乘积死锁）**：状态机决定每个迁移需要哪一级证据（`Shadow→Canary` 只需回放/影子非劣，`Canary→Active` 需在线配对 + 覆盖 + 支撑）；反过来，证据租约到期或漂移报警强制把 Active 降为 Degraded。多用户时把每个 persona 的状态机做**乘积**，契约交集为空 ⇔ 不存在同时满足所有 Active 证书的迁移 ⇔ 乘积自动机**死锁**。我们不把它当作例外分支，而当作可模型检查的 liveness 属性：死锁必经 `Negotiating`（输出最小让步集），`Negotiating` 必有界时间到达 `Active` 或 `Suspended`；`Arbitration` 选单一活跃 persona，其余降为 Canary 排队。于是 v20 里「静默放宽（不安全）」与「无限停机（不可用）」这两条危险旁路被显式状态吸收。

**耦合升级**：CLM（生命周期状态机）把 persona 契约编译成状态机实例并执行权威阶梯；CCE（对比证书引擎）为每次促权生成可审计、可随时停、控制 FWER 的证据包；CSCV（状态-对比验证器）对状态空间做模型检查、对迁移做交错 fuzz、对实验做统计审计。四层架构由 v8 升级为 v9：v8 的「仿真-检索-边缘飞轮 + 人格契约层 + 并发证书层」之上，插入 **证书生命周期层（L2.5）** 与 **证据层（L3.5）**。

## 1. 形式化定义（增量：定义 44–51）

**定义 44（证书生命周期状态机 CLSM）**：证书生命周期状态机 M = (Q, q_0, →, α, R)，其中 Q = {Draft, Calib, Shadow, Canary, Active, Degraded, Suspended, Retired}，q_0 = Draft；迁移关系 → ⊆ Q × Q × G × E，卫兵 g = (pred, r_min, budget) 由谓词、所需证据等级 r_min、预算约束组成；α: Q → [0,1] 为权威等级；E 为证据包空间。语义：每个证书实例在任意时刻恰处于一个状态；迁移只有在卫兵满足时原子发生；状态更新与证书谓词更新共享同一 epoch（复用 v20 定义 41/43 的快照机制）。**允许迁移**由一张显式白名单给出，默认拒绝（whitelist, fail-closed）。

**定义 45（权威阶梯与棘轮不变式）**：取 0 < α_d ≤ α_c < 1，定义 α(Draft)=α(Calib)=α(Shadow)=α(Suspended)=α(Retired)=0，α(Degraded)=α_d，α(Canary)=α_c，α(Active)=1。执行权 `Authority(c,q) = c ∩ scale(Π_u, α(q))`（速度/接触力/区域按 α 缩放或取子集）。两条不变式：
- **R1（权威不超过证据）**：q ∈ {Canary, Active} ⇒ 存在有效证据 e，使 rank(e) ≥ r_min(q) 且 e 的证据租约未过期、漂移未报警。
- **R2（棘轮）**：沿任意执行，若 α(q') > α(q) 则迁移必属完整促权链 `Shadow→Canary→Active`，且各步证据等级单调不减；若 α(q') ≤ α(q)，迁移可为降权迁移，**不要求新证据**，且单个硬违例/覆盖失效/租约到期即可触发。
**命题**：R2 排除 v20 中「Active 依时间续租、但证据已陈旧」的静默不 sound：租约到期只能触发降权，不能触发促权。

**定义 46（对比实验证书 CCE）**：配对实验设计 D = (S, b, π, δ, α, β, n_min)。S 为匹配场景/种子集合，按块 b = (persona, terrain, load, init_hash) 分层；每块内候选与现任共享初始状态（paired reset），配对差 d_i = m_cand(i) − m_inc(i)，安全指标取「越大越好」的 margin。原假设 H0: μ_d ≤ −δ，备择 H1: μ_d > −δ（非劣或更优）。**e-process**：{E_n} 满足 E_0 = 1、E_n ≥ 0 且在 H0 下为上鞅；由 Ville 不等式，P(∃n: E_n ≥ 1/α) ≤ α。**促权判据**：E_n ≥ 1/α ∧ 支撑证书有效 ∧ 块覆盖完整 ∧ 证据租约有效。与 v20 的「A/B 没回归」相比，结论在任意停止时刻仍有 Type-I 控制。

**定义 47（多重比较与证据合成）**：对 m 个 persona、k 个指标分别维护 e-process E^{(u,j)}。全局证据用加权平均/合并 E_global = Σ w_{u,j} E^{(u,j)}（Σw=1，权重**预注册**），或保守地用 Holm/Bonferroni 阈值 α/(mk)。**命题**：若各 E^{(u,j)} 在全局 H0（所有 persona 均非劣）下为非负上鞅，则加权平均仍为 H0 下的非负上鞅，故全局促权错误率 ≤ α。高风险 persona 获得更高先验权重，但权重不可见数据后调整。

**定义 48（证据租约与稳定窗口）**：证据 e = (E_n, t_e, T_ev, provenance, support)。仅当 `now − t_e ≤ T_ev` ∧ 漂移检测器未报警 ∧ support 有效时，e 可用于促权卫兵。到期**不是惰性续期**，而是强制 Active→Degraded 并重跑 CCE（先 Shadow 回放、再 Canary 在线）。**注**：对非平稳性采用「有效期 + 漂移复位」，而非对 e 值做指数衰减；后者会破坏可选停止下的鞅性质与有效性。

**定义 49（多用户乘积自动机与 liveness）**：全局状态 Q_global ⊆ (∏_u Q_u) × Q_arb，Q_arb = {Idle, Negotiating, Arbitration}。契约交集为空 ⇔ 不存在同时满足所有 Active 证书的迁移 ⇔ 乘积自动机死锁。要求两条 liveness 属性：
- L1：`AG(deadlock ⇒ AF_{≤Δ} Negotiating)`——死锁必须在有界时间内进入协商；
- L2：`AG(Negotiating ⇒ AF_{≤T_neg} (Active ∨ Suspended))`——协商必须有界时间给出结果。
`Negotiating` 输出最小让步集；`Arbitration` 选单一活跃 persona，其余降为 Canary 排队。**命题**：若 L1/L2 在模型检查中成立，则系统不存在「静默放宽」或「无限停机」的第三条路，二者都被显式状态吸收。

**定义 50（迁移 soundness 与状态-证据联合不变式）**：**定理**：若 (i) 所有促权卫兵使用的 CCE 在其 sound 域内且非劣结论有效；(ii) 所有执行路径满足 R1/R2；(iii) 证书谓词本身 sound（沿用 v20 定义 38–43）；(iv) 状态迁移与证书更新在同一 epoch 原子提交；则任意可达配置 (q, c) 满足 `Authority(c,q) ⊆ C_global ∩ Π_u`，且 q ∈ {Canary, Active} ⇒ 覆盖/非劣证据有效。**证明**：对迁移序列归纳。基例 q_0 无执行权；促权步由 (i)(ii) 得证据等级达标且权威不超证据；降权步权威单调不增、由 (iii) 保持证书仍 ⊆ C_global；并发撕裂由 (iv) 的 epoch 一致性排除。

**定义 51（回放证据的支撑条件）**：反事实回放用日志策略 μ 采样的轨迹评估候选 π。若在支撑集上 ∀s,a: μ(a|s)=0 ⇒ π(a|s)=0，且重要性权重 π(a|s)/μ(a|s) ≤ W_max（support certificate），则加权配对差的 e-process 仍有效；否则回放只能作为 Shadow 的辅助信号，**不得单独触发促权**。此定义把「仿真/日志对比」与「真机在线对比」分层，防止离线证据冒充在线授权。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-60 CERT-LIFECYCLE-MACHINE（证书生命周期状态机 CLM）
1. **状态机实例化**：把 persona 契约 Π_u 与全局证书 C_global 编译为 CLSM 实例；显式迁移白名单、权威阶梯 α(q)、每级所需证据等级 r_min。
2. **棘轮执行器**：促权走完整链并检查历史（禁止 `Shadow→Active` 跳级）；降权由违例/漂移/租约到期/证据过期即时触发，且不消耗信任预算。
3. **迁移事务**：状态与证书谓词共享 epoch 原子提交；迁移事件写入可线性化审计日志，供 CSCV 重放。
4. **多用户乘积与仲裁**：乘积自动机 + Negotiating/Arbitration；空交集走最小让步协商或有界仲裁，绝不静默放行。

### 2.2 IP-61 COMPARATIVE-CERT-ENGINE（对比证书引擎 CCE）
1. **预注册实验模板**：在收集数据前固定 (δ, α, β, n_min, blocks, 指标方向, 权重)，哈希入库；运行时只允许按模板执行。
2. **配对非劣 e-process**：有界配对差的 Hoeffding e-value 递推；任意停止时刻 Type-I ≤ α；报告当前 e 值与隐含置信序列。
3. **FWER 控制与证据合成**：多 persona/多指标独立 e-process + 预注册权重合并，或 Holm/Bonferroni 保守阈值。
4. **支撑证书与回放分层**：检查 positivity 与权重上界；无支撑时自动降级为 Shadow 辅助证据，禁止促权。
5. **证据租约与漂移复位**：T_ev 到期或漂移报警即作废证据并把 Active 降为 Degraded。

### 2.3 IP-62 CERT-STATE-COMPARATIVE-VALIDATOR（状态-对比验证器 CSCV）
1. **状态机模型检查**：可达性（Active 只能经 Shadow/Canary 到达）、死锁自由、L1/L2 liveness、权威单调性。
2. **迁移模糊测试**：枚举非法迁移尝试、并发迁移、epoch 撕裂、证据过期竞态；断言默认拒绝。
3. **对比实验审计**：检查预注册一致性、可选停止合法性、配对完整性、多重比较是否校正、报告是否选择性。
4. **回放支撑检查**：构造零支撑/重尾权重场景，验证系统不会误促权。

## 5. 本轮最大风险

**一句话**：状态机只能保证「证书迁移在证据层合法」，对比实验也只在「配对可交换 + 场景平稳 + 回放有支撑」时成立；一旦这些前提被分布漂移、选择性报告或零支撑回放破坏，CLSM 反而会给不 sound 的证书盖上「合法迁移」的章，因此 E96（假促权）与 E101（回放支撑）必须设为红线，且默认回退到「Shadow-only + 纯收缩、零促权」这条永不失 sound 的底线。

### IP-60 CLM：状态、权威阶梯与棘轮迁移
```
STATES  = ["Draft","Calib","Shadow","Canary","Active","Degraded","Suspended","Retired"]
ALPHA   = {"Draft":0,"Calib":0,"Shadow":0,"Canary":0.3,"Active":1.0,
           "Degraded":0.3,"Suspended":0,"Retired":0}
R_MIN   = {"Canary":1,"Active":2}          # 证据等级：1=影子/回放非劣, 2=在线配对非劣
ALLOWED = {
  "Draft":     {"Calib"},
  "Calib":     {"Shadow","Suspended"},
  "Shadow":    {"Canary","Degraded","Suspended"},
  "Canary":    {"Active","Degraded","Suspended"},
  "Active":    {"Degraded","Suspended","Retired"},
  "Degraded":  {"Shadow","Suspended","Retired"},   # 只能回到 Shadow 重新攒证据
  "Suspended": {"Calib","Retired"},
  "Retired":   set(),
}

def expands_authority(q, q_to):
    # 注意：Degraded→Shadow 是收缩；只有 Canary/Active 方向才算扩张
    return (q, q_to) in {("Shadow","Canary"),("Canary","Active")}

def lifecycle_transition(cert, q_to, evidence, now):
    q = cert.state
    if q_to not in ALLOWED[q]:
        return reject("illegal edge")                       # fail-closed
    if expands_authority(q, q_to):
        if not evidence_ok(evidence, R_MIN[q_to], now):
            return reject("insufficient evidence")
        if q_to == "Active" and not cert.history.contains(["Shadow","Canary"]):
            return reject("ratchet: promotion chain skipped")
    # 状态与证书谓词同 epoch 原子提交（复用 IP-58 快照）
    with epoch_transaction(cert) as tx:
        tx.state     = q_to
        tx.predicate = recompute_predicate(cert, q_to)      # Authority(c,q)
    audit.append((now, q, q_to, evidence.id if evidence else None, cert.epoch))
    return accept

def safety_demote(cert, ev, now):
    if ev.hard_violation:                      target = "Suspended"
    elif ev.drift or ev.evidence_expired or ev.lease_expired: target = "Degraded"
    else: return
    lifecycle_transition(cert, target, evidence=None, now=now)   # 降权免费，不看证据
```

### IP-61 CCE：配对非劣 e-process、FWER、支撑与证据租约
```
import math

def cce_step(E, d, delta, B, lam):
    # H0: mu_d <= -delta; x = d + delta 在 H0 下均值 <= 0，范围 [delta-B, B+delta]
    c = 2*B + delta
    return E * math.exp(lam*(d + delta) - (lam*lam*c*c)/8.0)   # Hoeffding e-value

def paired_cce(candidate, incumbent, blocks, design):
    E, n = 1.0, 0
    for block in blocks:                       # 块内 paired reset，共享初态与种子
        for i in block:
            d = margin(candidate, i) - margin(incumbent, i)
            E = cce_step(E, d, design.delta, design.B, design.lam)
            n += 1
    return Evidence(e_value=E, n=n, alpha=design.alpha,
                    rank=(1 if n >= design.n_min else 0),
                    provenance=design.hash, t_e=now())

def promotion_ok(ev, need, now):
    if ev is None or now - ev.t_e > ev.T_ev: return False   # 证据租约
    if drift_alarm(): return False                           # 漂移复位
    if not ev.support_ok: return False                       # 回放支撑
    if need == 1: return ev.rank >= 1
    return ev.rank >= 2 and ev.n >= ev.n_min and ev.e_value >= 1/ev.alpha

def global_evidence(Es, weights):
    # 预注册权重，Σw=1；各 E 在全局 H0 下为上鞅 ⇒ 加权平均仍为上鞅
    assert abs(sum(weights)-1.0) < 1e-9 and all(w > 0 for w in weights)
    return sum(w*E for w, E in zip(weights, Es))

def support_certificate(logs, pi, mu, W_max):
    max_w = 0.0
    for (s, a) in logs:
        if pi(a|s) > 0 and mu(a|s) <= 0:
            return None                                      # positivity 失败
        if mu(a|s) > 0:
            w = pi(a|s) / mu(a|s)
            if w > W_max: return None                        # 重尾权重
            max_w = max(max_w, w)
    return SupportCert(W_max=max_w)

def replay_evidence(logs, pi, incumbent, design):
    sup = support_certificate(logs, pi, logs.behavior_policy, design.W_max)
    if sup is None:
        return Evidence(rank=0, role="shadow_only")          # 禁止单独促权
    E, n = 1.0, 0
    for block in blockify(logs, design.blocks):
        for i in block:
            d = margin(pi, i) - margin(incumbent, i)
            E = cce_step(E, d, design.delta, design.B, design.lam); n += 1
    return Evidence(e_value=E, n=n, alpha=design.alpha,
                    rank=(1 if n >= design.n_min else 0), support_ok=True)
```

| 回放支撑不足/权重重尾，离线证据冒充在线授权 | 高 | E101 红线；support certificate + W_max；无支撑仅作 Shadow 辅助 |
| 多用户乘积状态爆炸，模型检查无法完成或漏检 | 中-高 | 限 m≤3、对称约简、assume-guarantee 分解；E99/E100 双门槛 |
| 棘轮过严导致「促权饥饿」：安全策略永远进不了 Active | 中 | 预注册权重与自适应 λ；分 persona 逐步放量；监控促权失败率并调 δ/样本量 |
| 状态与证据双日志在并发下撕裂，迁移与谓词不一致 | 中 | 同 epoch 原子提交；CSCV 线性一致性重放；seqlock 重试/降级 |
| 多重比较校正后 power 不足，实验永远不显著 | 中 | 分层预注册 + 稀疏对照；必要时用 e-value merging 替代 Bonferroni |
| 证据包/预注册哈希被篡改或张冠李戴 | 中 | 设计哈希绑定 experiment_id + persona + 硬件版本；入库前验签 |

## 6. 本轮最大风险

**一句话**：状态机只能保证「证书迁移在证据层合法」，对比实验也只在「配对可交换 + 场景平稳 + 回放有支撑」时成立；一旦这些前提被分布漂移、选择性报告或零支撑回放破坏，CLSM 反而会给不 sound 的证书盖上「合法迁移」的章——因此 E96（假促权）与 E101（回放支撑）必须设为红线，且默认回退到「Shadow-only + 纯收缩、零促权」这条永不失 sound 的底线。
