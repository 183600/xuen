# 第 1 轮（灵感循环 v2：「长期记忆」×「技能组合」）—— 从「整任务策略」到「技能字母表 + 程序性记忆」

> **方向判断**：上一轮 UIP-01~10 把注意力放在「推理时怎么验证、怎么重试、怎么拿步骤分」——属于**策略调度层**。但它有两个未言明的假设：**每个任务是一个不可分的整体**，失败只能整任务重试；**经验只存在于当前 episode**，`reset()` 后一切归零。本轮把这两个假设拆掉：32 个任务很可能是**少量技能的重复组合**；跨 episode 真正值得记住的不是「杯子在哪」，而是「这类物体在这种关系下用哪个技能、失败后怎么恢复」。核心命题：**用「技能字母表」压缩任务空间，用「程序性记忆」压缩经验空间，二者相乘得到测试时学习（test-time learning）能力，且完全落在远程 API 权限内。**

---

## 0. 承接事实与新增结构性观察

承接想法区 §0 的赛制事实（32 任务、平均成功率 + 步骤分、N 端口、延迟/动作规律性计入可信度、单模型多任务、5 条泛化轴）。本轮新增的是**结构性观察**，不是新外部事实：

| 观察 | 内容 | 依据 |
|---|---|---|
| 任务可分解 | 32 个任务名中，绝大多数可写成「接近→抓取→搬运→放置/插入/倒/折/拉」的序列；真正独特的技能只有插入、拔出、旋转、倾倒、折叠、拉链、悬挂、堆叠等少数几个 | 任务名逐条分解（产物区 §1.1，**假设性分解，待数据验证**） |
| 数据集无技能标签 | LeRobot 数据集只给 episode 级语言与轨迹，没有技能分段标签 | 数据集卡片（承接 §0） |
| 接口有 `reset()` | 每个 episode 可重置；进程在 N 个端口上长期运行 | `unibot_submission` README（承接 §0） |
| 单模型约束 | 不能靠「32 个模型投票」；技能组合必须是**同一骨干内的条件化** | 承接上一轮 UIP-03 的判断 |
| 记忆可用性待核实 | 评测是否在同一进程/同一容器内连续跑多个 episode、是否允许落盘持久化，尚未从 README 明确 | **工作假设 H5，待核实** |

## 1. 直觉解释（先给直觉）

1. **32 个任务不是 32 个函数，而是一门语言里的 32 个句子。** 把「抓取」学会一次，可以用在 ArrangePlates、StackBowls、FruitCollection、PackPhone……上；把「插入」学会一次，可以用在 PlugCharger、PlugInEthernet、ArrangeTestTubes 上。任务的差异更多在**物体、容器、关系、顺序**，而不在底层动作。若这个直觉成立，技能字母表就是最强的数据效率杠杆：每个技能能见到来自多个任务的演示，而不是每个任务各训一个头。

2. **长期记忆不该记坐标，该记「技能的条件-结果」。** 记住「上次杯子在 (x,y)」在换背景、换位置、换物体后立刻失效，而且会把评测集的位置信息背下来，属于最危险的过拟合。真正可迁移的是**程序性知识**：圆柱体侧面抓比顶抓稳；插头横向偏移超过 5 mm 时先回退再对齐；毛巾折叠要先抓远边。这类知识在 5 条泛化轴上更稳定。

3. **记忆 + 组合 = 不更新梯度的测试时学习。** 每个 episode 结束后，只更新「技能成功率、失败签名、恢复规则」这几个计数器；下一个 episode 检索更好的计划。这不需要重新训练，天然适合「远程 API、真机评测、不能在家反复试」的赛制。

4. **组合的是技能，不是模型。** 为满足单模型约束，技能不是 32 个独立网络，而是同一 VLA 骨干上的**技能令牌 / 技能 prompt / LoRA 专家**；组合器只决定「现在调用哪个技能、参数是什么」，不引入第二个动作模型。

5. **排行榜口径决定了组合器要「先保步骤分，再冲成功率」。** 一个计划即使最终失败，只要按顺序完成了前面的计分步，仍能拿部分分；因此组合器应优先选择「前置计分步确定、失败可局部恢复」的计划，而不是「一步到位但脆弱」的长程计划。这与上一轮 UIP-02 的安全网直接对接。

**与「纯 VLA 微调」「轨迹 RAG」的区别**：纯 VLA 没有显式技能结构，32 个任务各 ~1000 条演示，样本效率低；轨迹 RAG 检索的是原始轨迹，检索结果天然带坐标与场景外观，正是 5 条泛化轴最脆弱的东西。本轮检索的是**技能级程序知识**（在什么条件下、哪个技能、成功率多少、失败后怎么恢复），组合的是**技能**而不是动作或轨迹。

## 2. 严谨定义（再给定义）

**定义 1（技能）** 技能
`σ = (π_σ, Pre_σ, Post_σ, Inv_σ, Δ_σ, C_σ)`，
其中 `π_σ: O×G→A` 是由单一 VLA 骨干以技能令牌 `z_σ` 条件化的闭环策略；`Pre_σ, Post_σ` 是观测上的谓词（可观测、可验证）；`Inv_σ` 是安全不变式（不碰撞、不超力、不越界）；`Δ_σ` 是最大执行步数；`C_σ` 是延迟/能耗代价。

**定义 2（组合计划）** 计划由以下语法生成：

```
P ::= σ | P;P | repeat(P,n) | repeat_until(P,φ) | if(φ,P,P) | try(P,R)
```

`P;Q` 表示顺序执行；`try(P,R)` 表示 P 失败时执行恢复计划 R。计划的**可组合性条件**是：对相邻技能 `σ_i, σ_{i+1}`，要么 `Post_{σ_i} ⇒ Pre_{σ_{i+1}}`，要么存在修复算子 `R_i` 使 `Post_{σ_i} ⇒ Pre_{R_i}` 且 `Post_{R_i} ⇒ Pre_{σ_{i+1}}`。否则计划无效，必须重规划。

**定义 3（程序性记忆项）** 记忆项
`m = (σ, κ, n, α, β, Φ, ρ, t_0, h, V)`，
其中 `κ` 是**语义上下文键**（语言嵌入 + 物体可供性 + 空间关系 + 容器类型，**不含绝对坐标**）；`n=α+β` 是支撑样本数；`α,β` 是 Beta 成功/失败计数；`Φ: 失败签名→恢复技能`；`ρ` 是来源链（哪些任务/数据集/episode）；`t_0` 是写入时间；`h` 是新鲜度；`V` 是有效谓词（版本匹配、域距离、未被证伪）。

**定义 4（记忆检索）** 给定当前上下文 `κ_t`，检索得分

```
Ψ(m|κ_t) = sim(κ_t, m.κ) · h(m) · V(m) · [ μ(m) + c·sqrt(ln N / n(m)) ]
μ(m) = α/(α+β)
```

按 `Ψ` 取 top-k。`sim` 用冻结的文本/视觉嵌入，不用像素坐标。`c` 控制探索；在比赛后期可退化为纯利用。

**定义 5（组合可靠性下界）** 对计划 `P=σ_1;...;σ_n`，设每个技能的成功率下界为 `p_i^-`（由 Beta 后验的 `1-δ` 分位数给出），前置条件失配概率为 `ε_i`，则由并集界

```
P(P 成功) ≥ max(0, 1 - Σ_i (1-p_i^-) - Σ_i ε_i)
```

该下界保守但可审计；它把「记忆中的技能统计」转成「计划级风险」，用于拒绝高风险计划。

**定义 6（组合目标）**

```
P* = argmax_P  E[Score(P)] - λ·Risk(P)
s.t.  Latency(P) ≤ B_lat,  P(P成功) ≥ p_min,  Inv 不被违反
```

`Score` 是步骤分代理（UIP-02），`Risk` 用 CVaR 或失败概率。`λ` 随剩余时间/领先落后调整：领先时更保守，落后时更激进（与排行榜博弈一致）。

**定义 7（记忆更新与护栏）** 仅当验证器置信度 `conf ≥ τ` 且连续两次判定一致时更新：

```
α ← α + 1[success],  β ← β + 1[failure]
Φ ← Φ ∪ {(signature(o,σ), r*)}
```

若检测到域漂移（成功率骤降 / 验证器置信度下降 / 上下文超出记忆覆盖），则**冻结**该记忆项并降低检索权重，直到重新验证。

## 3. 瓶颈假设（工作假设，待实验证伪）

- **H1（技能可压缩）**：少量技能覆盖 32 任务的大部分方差。若每个任务都需要独特技能，组合收益会大幅缩水。
- **H2（技能可切分）**：技能边界能从夹爪开合、末端速度/接触、物体状态变化中较可靠地切出。若切分噪声大，字母表不可用。
- **H3（失败签名可复用）**：同类失败（抓偏、插偏、滑落、遮挡）在不同任务间有稳定的可观测签名，恢复技能可迁移。
- **H4（延迟可隐藏）**：记忆检索与验证器的开销能藏在 `action_chunk_size` 的执行窗口内；否则 p99 延迟上升会触发可信度质疑。
- **H5（记忆可跨 episode）**：评测在同一进程/容器内连续跑多个 episode，且允许 best-effort 落盘；若每个 episode 都是全新进程，则只能使用离线冷启动记忆。
- **H6（语义记忆优于坐标记忆）**：程序性记忆在 5 条泛化轴上比坐标记忆更稳；若记忆反而放大分布偏移，则应关闭在线更新，只保留离线先验。

## 5. 与上一轮 UIP-01~10 的分层关系（不推倒，做叠加）

- **UIP-01 RHPV-V** → 升级为 PMSC 的**技能后置条件验证器**：从「整任务子目标」下沉到「技能级 Post」，验证更局部、更便宜。
- **UIP-02 SSG** → 成为组合器的**目标函数**：优先选择能锁定前置计分步的计划。
- **UIP-03 MoA-Router** → 从「任务路由」升级为「技能条件化」：不是给每个任务一个专家，而是给每个技能一个令牌。
- **UIP-05 LCAG** → 成为组合器的**语言前端**：把指令解析成 `(物体, 可供性, 关系)`，用于生成技能参数与记忆键。
- **UIP-07 RRV** → 扩展为 UIP-17 MSH：增加技能切分、记忆命中率、组合成功率三类代理指标。
- **UIP-08 LAT-ENG** → 为记忆检索与技能切换提供**预取/缓存/异步**，保证 p99 不超预算。
- **UIP-09 DCR** → 作为 `try(P,R)` 中的特殊恢复技能（暂停-等待-重抓）。
- **UIP-10 CTRL-ARB** → 变成技能级属性：`INSERT/PULL` 偏 `ee`，`POUR/FOLD` 偏 `joint`，由技能定义携带。

## 6. 本轮最大风险（一句话）

**最大风险是「技能切分 + 记忆写入」两处噪声相乘：切分错了会把不同技能的数据混进同一个统计，验证器误判会把错误结果写进长期记忆，二者在跨 episode 复用时会形成自我强化的错误先验；若不做置信门控、双重验证、漂移冻结和离线回放校准，PMSC 会「越用越自信地错」，在 5 条泛化轴上反而比无记忆的整任务策略更差。**

### 1.2 程序性记忆模式

记忆项不存轨迹、不存坐标，只存「技能在什么语义条件下、成功率多少、失败后怎么恢复」：

| 字段 | 含义 | 示例 |
|---|---|---|
| `σ` | 技能 | `INSERT` |
| `κ` | 语义上下文键 | `{物体: 圆柱形插头, 关系: 轴向, 容器: 端口, 朝向: 水平}` |
| `α, β` | Beta 成功/失败计数 | `18, 4` |
| `μ` | 成功率均值 | `0.82` |
| `Φ` | 失败签名 → 恢复技能 | `横向偏移>5mm → RE_ALIGN` |
| `ρ` | 来源链 | `PlugInEthernet(12), PlugCharger(3)` |
| `t_0, h` | 写入时间 / 新鲜度 | `... / 0.93` |
| `V` | 有效谓词 | `版本匹配 ∧ 域距离<ε ∧ 未被证伪` |

**三层记忆**：

- **语义记忆 `M_sem`**：物体形状/材质/关系 → 技能先验（如「圆柱体侧抓优于顶抓」「织物先抓远边」）。来自训练数据的统计，跨任务复用。
- **程序记忆 `M_proc`**：技能成功率、失败签名、恢复规则、计划模板。跨 episode 更新。
- **工作记忆 `M_work`**：当前 episode 的子目标、已试技能、失败次数。`reset()` 时清空，**不跨 episode**。

> **关键设计**：跨 episode 的长期记忆只允许 `M_sem` 与 `M_proc`，且键 `κ` 不含绝对坐标；任何「场景坐标 / 物体实例 ID / 评测集指纹」都不入库。这是防止把评测集背下来的硬约束。

### 1.3 组合器与可靠性下界

组合器分四步：

1. **上下文编码**：`κ_t = Enc(l, scene_graph(o_t))`，其中 `scene_graph` 由 UIP-05/13 的 `(物体, 可供性, 关系)` 构成。
2. **记忆检索**：按定义 4 取 top-k 技能统计与恢复规则。
3. **计划展开**：从任务模板库（离线从成功演示中提取）展开候选计划；对每个技能用记忆中的成功率与恢复规则实例化 `try(σ, R)`；必要时用 `repeat_until` 处理多物体。
4. **风险敏感选择**：用定义 5 的组合可靠性下界过滤 `P(P成功) < p_min` 的计划，再用定义 6 的目标函数选 `P*`。

**组合可靠性下界的用途**：

- 拒绝「长程但脆弱」的计划（例如 5 个技能串联、每个成功率 0.7，则下界可能低于 0.3）。
- 优先「短程 + 可恢复」的计划（例如先完成 2 个高确定技能锁定步骤分，再尝试低确定技能）。
- 在排行榜语境下，这等价于**显式优化步骤分的下尾**，而不是只看成功率均值。

### 1.4 伪代码

```python
# 工具函数（离线实现）：freshness, sim, beta_lower, now,
# expected_step_score, cvar_failure, risk_aversion,
# remaining_time, score_gap, precondition_mismatch

@dataclass
class Skill:
    name: str
    token: int
    pre: Callable[[Obs], bool]
    post: Callable[[Obs], bool]
    inv: Callable[[Obs], bool]
    max_steps: int
    prior: float = 0.5          # 无记忆时的保守成功率先验

@dataclass
class MemoryItem:
    skill: str
    key: np.ndarray             # 语义上下文嵌入，不含坐标
    alpha: float
    beta: float
    recoveries: dict            # failure_signature -> recovery skill
    provenance: list
    t0: float
    valid: bool

class ProceduralMemory:
    def __init__(self, tau=0.6, c=0.5, h_min=0.2, n0=2.0, recovery_table=None):
        self.items, self.tau, self.c, self.h_min, self.n0 = [], tau, c, h_min, n0
        self.recovery_table = recovery_table or {}   # 离线统计的签名→恢复技能
        self.N = 0

    def match(self, skill, key, min_n=2):
        # 分层 backoff：精确键 → 同技能最近键 → None（回退任务级先验）
        cands = [m for m in self.items
                 if m.skill == skill and m.valid and m.alpha + m.beta >= min_n]
        if not cands:
            return None
        return max(cands, key=lambda m: sim(key, m.key))

    def retrieve(self, key, topk=8):
        out = []
        for m in self.items:
            if not m.valid:
                continue
            h = freshness(m.t0)
            if h < self.h_min:
                continue
            n = m.alpha + m.beta
            mu = m.alpha / n
            ucb = mu + self.c * math.sqrt(math.log(self.N + 1) / n)
            out.append((sim(key, m.key) * h * ucb, m))
        return [m for _, m in sorted(out, key=lambda x: -x[0])[:topk]]

    def update(self, skill, key, success, signature=None, conf=1.0):
        if conf < self.tau:                     # 置信门控：低置信不写
            return
        m = self.match(skill, key)
        if m is None:
            m = MemoryItem(skill, key, self.n0, self.n0, {}, [], now(), True)
            self.items.append(m)
        if success:
            m.alpha += 1
        else:
            m.beta += 1
            if signature is not None:
                r = self.recovery_table.get(signature)
                if r is not None:
                    m.recoveries[signature] = r
        self.N += 1

    def recoveries_for(self, skill, key, signature):
        m = self.match(skill, key)
        return None if m is None else m.recoveries.get(signature)

class PMSCPolicy:
    def __init__(self, vla, planner, verifier, memory, templates, k=4,
                 tau=0.6, p_min=0.3, max_recovery=2, latency_budget_ms=200):
        self.vla, self.planner, self.verifier, self.memory = vla, planner, verifier, memory
        self.templates = templates
        self.k, self.tau, self.p_min = k, tau, p_min
        self.max_recovery, self.budget = max_recovery, latency_budget_ms

    def reset(self):
        self.vla.reset()
        self.plan, self.pc, self.buf, self.recovery = None, 0, [], 0
        self.key = None
        self.work = {}                          # 只在本 episode 内

    def get_action(self, obs):
        if self.plan is None:
            self.plan = self.compose(obs)
        if not self.buf or self._need_advance(obs):
            self._advance(obs)
        if not self.buf:
            sigma = self.plan[self.pc]
            chunk = self.vla.get_action(obs, skill_token=sigma.token)  # (T_a, ...)
            self.buf = list(chunk[: self.k])                            # 只承诺 k 步
        return self.buf.pop(0)

    def compose(self, obs):
        self.key = self.encode_context(obs)     # language + affordance + relation
        mem = self.memory.retrieve(self.key, topk=8)
        plans = self.planner.expand(obs, mem, templates=self.templates)
        feasible = [p for p in plans
                    if plan_success_lb(p, self.memory, self.key) >= self.p_min]
        return max(feasible or plans, key=lambda p: self._objective(p, obs))

    def _need_advance(self, obs):
        sigma = self.plan[self.pc]
        ok, conf = self.verifier(obs, sigma.post)
        if conf >= self.tau and ok:
            self.memory.update(sigma.name, self.key, True, conf=conf)
            return True
        fail, fconf = self.verifier(obs, sigma.post, mode="failure")
        if fconf >= self.tau and fail:
            self.memory.update(sigma.name, self.key, False,
                               signature=self._signature(obs), conf=fconf)
            return True
        return len(self.buf) == 0 and self._timeout(obs)

    def _advance(self, obs):
        sigma = self.plan[self.pc]
        ok, conf = self.verifier(obs, sigma.post)
        if conf >= self.tau and ok:
            self.pc += 1
            self.recovery = 0
            self.buf = []
            return
        if self.recovery < self.max_recovery:
            sig = self._signature(obs)
            r = self.memory.recoveries_for(sigma.name, self.key, sig)
            if r is not None:
                self.plan.insert(self.pc, r)    # 局部恢复，不整任务重试
                self.recovery += 1
                self.buf = []
                return
        self.plan = self.compose(obs)           # 恢复失败 → 从当前状态重规划
        self.pc, self.recovery, self.buf = 0, 0, []

    def _objective(self, plan, obs):
        score = expected_step_score(plan, self.memory, self.key)
        risk = cvar_failure(plan, self.memory, alpha=0.2)
        lam = risk_aversion(remaining_time(obs), score_gap(obs))
        return score - lam * risk

def plan_success_lb(plan, memory, key, delta=0.1):
    miss = 0.0
    for i, sigma in enumerate(plan):
        m = memory.match(sigma.name, key)
        p = beta_lower(m.alpha, m.beta, delta) if m else sigma.prior
        miss += 1.0 - p
        if i + 1 < len(plan):
            miss += precondition_mismatch(plan[i], plan[i + 1])
    return max(0.0, 1.0 - miss)
```

### 1.5 护栏与延迟工程

| 护栏 | 作用 | 默认值（起点） |
|---|---|---|
| `tau` | 验证器置信度门限；低置信不推进、不写记忆 | 0.6 |
| 双重验证 | 连续两帧 / 语义 + 几何两通道一致才写记忆 | 2 次一致 |
| `max_recovery` | 每个技能最多局部恢复次数 | 2 |
| `p_min` | 组合可靠性下界门限 | 0.3 |
| `k` | 只承诺 k 步，限制盲走 | 4 |
| `plan_len` | 计划最大技能数，防止长程误差累积 | 8 |
| `budget` | 单步延迟预算；超预算降级为模板组合器 | 200 ms |
| `V` / 漂移检测 | 成功率窗口骤降则冻结记忆项 | 窗口 20，降幅 >20% |

**延迟设计**：

- 记忆检索：小规模 FAISS/字典 top-k，<1 ms；记忆库按任务/技能分层，避免全库扫描。
- 验证器：小 VLM（3B 级）或几何规则，20–50 ms；每 `k` 步异步跑一次，结果双缓冲，`get_action` 只读最近结果。
- 组合器：episode 开始时跑一次；技能失败时跑一次；模板匹配 + 小模型，结果缓存。
- 目标：新增 p99 延迟 < 20–30 ms；若超预算，关闭在线组合，退回「固定任务模板 + UIP-01 重试」。

## 2. UIP-12 · SSA（Skill Segmentation & Annotation）

**问题**：数据集只有 episode 级语言与轨迹，没有技能标签；没有字母表，组合无从谈起。

**切分信号**（多信号投票，降低单信号噪声）：

- 夹爪开合事件（open→close→open）；
- 末端速度/加速度的「接近-减速-停顿-抬起」剖面；
- 物体状态变化（VLM 前后帧描述差异、场景图节点变化）；
- 任务模板的先验长度（如 `A→G→T→PL` 的典型步数）。

**方法**：

1. 对每个 episode 做变点检测（PELT / 贝叶斯变点）得到候选边界；
2. 用夹爪事件与场景图变化对齐边界；
3. 对片段做无监督聚类（DTW / 嵌入聚类），得到技能簇；
4. 用任务模板给簇命名（人工抽检 + 主动学习）；
5. 输出：`(episode_id, t_start, t_end, skill_label, pre/post 帧)`。

**输出用途**：训练技能令牌（UIP-16）、构建记忆冷启动（UIP-13）、回放评测（UIP-17）。

**风险**：切分错误会把不同技能混入同一统计；用多信号一致性 + 人工抽检 + 下游组合成功率反向校验。

## 3. UIP-13 · SMM（Skill-Memory Matrix）

**冷启动**（离线，来自 32 个训练数据集）：

- 用 UIP-12 的技能片段统计每个 `(skill, κ)` 的成功率；
- 成功/失败标签来自演示是否完成 + 末帧场景图检查；
- 失败签名从失败片段中聚类（若数据集只有成功演示，则用合成扰动/回放注入失败）。

**在线更新**（评测时）：

- 只更新 `M_proc` 的 Beta 计数与恢复规则；
- 共享 `M_sem/M_proc`（语义/程序知识），**隔离 `M_work`**（每端口/每 episode）；
- 落盘 best-effort：`sqlite`/JSONL；若进程重启，回退到冷启动。

**分层键**：`κ = (task, object_class, relation, receptacle_type)`，检索时支持 backoff（精确 → 物体类 → 任务级 → 全局），避免稀疏键永远命中不到。

**风险**：键冲突/稀疏；用分层 backoff + 最小样本数 `n_min`，不足则回退到任务级先验。

## 4. UIP-14 · CRB（Composition Reliability Bound）

**机制**：用 Beta 后验的 `1-δ` 下分位数 `p_i^-` 作为技能成功率下界，再用并集界

```
P(P成功) ≥ max(0, 1 - Σ_i (1-p_i^-) - Σ_i ε_i)
```

过滤计划。`ε_i` 是前置条件失配概率，可用验证器在回放数据上的误判率估计。

**校准**：在离线回放上比较「预测下界」与「实际计划成功率」，用可靠性图/ECE 校准 `δ`；若下界过保守（大量好计划被拒），提高 `δ` 或改用「按技能独立假设的乘积下界 + 保守惩罚」。

**用途**：

- 计划选择：`P(P成功) ≥ p_min`；
- 步骤分优化：优先短程、可恢复、前置计分步确定的计划；
- 风险沟通：给每个计划一个可审计的成功概率下界，而不是拍脑袋。

**风险**：并集界过保守，导致组合器只选 1–2 个技能、放弃长程任务；用回放校准 + 分任务阈值缓解。

---

## 5. UIP-15 · RSP（Recovery Skill Prior）

**失败签名表**（可观测、可聚类）：

| 签名 | 可观测信号 | 恢复技能 |
|---|---|---|
| 横向偏移 | 目标中心与夹爪轴线偏差 > τ | `RE_ALIGN` |
| 高度偏差 | 抓取点高于/低于目标 > τ | `RE_APPROACH` |
| 抓空/滑落 | 夹爪闭合但物体未随动；夹爪宽度异常 | `RE_GRASP` |
| 遮挡 | 目标区域置信度骤降；机械臂遮挡头部视野 | `RETREAT` + `RE_OBSERVE` |
| 碰撞/受阻 | 关节电流/力矩异常（若可得）或动作被阻 | `RETREAT` |
| 错物体 | 语义匹配分数低；场景图节点不符 | `RE_SELECT` |
| 超时 | 技能执行步数 > `Δ_σ` | `RE_PLAN` |

**机制**：`try(σ, R)`；R 由 `M_proc.Φ` 检索，最多 `max_recovery` 次；恢复失败则从当前状态重规划，而不是整任务重试。相比 UIP-01 的整任务重试，恢复是**局部**的：只重做失败的技能，已完成的计分步不丢。

**风险**：错误恢复导致动作跳变/循环；限制恢复次数、恢复动作平滑、恢复后必须重新验证后置条件。

## 6. UIP-16 · STC（Skill Token Conditioning）

**目标**：在单模型约束下实现技能组合。

**两条路线**：

1. **训练式**：在 VLA 骨干上加技能令牌嵌入 `z_σ`（或轻量 LoRA 专家），用 UIP-12 的技能标签训练；所有技能共享骨干，只有令牌/适配器不同——仍是一个模型。
2. **免训练式**：把技能描述前置到语言指令（如 `"skill: insert; object: ethernet plug; target: port; align: horizontal"`），用预训练 VLA 的指令跟随能力执行；组合器只切换 prompt。这是最保守、最容易落地的路线。

**风险**：技能令牌相互干扰/灾难遗忘；用平衡采样、令牌 dropout、共享骨干 + 小适配器；免训练式则受限于 VLA 的指令跟随能力。

## 7. UIP-17 · MSH（Memory-Skill Harness）

**三级回放**（诚实面对「离线无法完全闭环」）：

1. **计划级回放**：在演示数据上比较「组合器预测的技能序列」与「UIP-12 标注的技能序列」；指标：序列准确率、编辑距离、步骤分代理。
2. **验证器回放**：在留出帧上测每个技能 `Post` 的 precision/recall；指标：误判率、漏判率、置信度校准（ECE）。
3. **世界模型 rollout**：用 UIP-04 WMA-MPC 或学习动力学模型做闭环代理；再用有限真机时段校准。没有世界模型时，至少做「观测回放 + 动作扰动」的敏感性分析。

**5 轴扰动套件**（承接 UIP-07/17 的思路）：位置、干扰物、背景、未见物品、人为干扰；每轴单独切分，报告逐轴成功率与步骤分代理。

**记忆专项指标**：

- 记忆命中率（top-k 中是否存在正确技能/恢复）；
- 冷启动 vs 在线更新 vs 无记忆的样本效率；
- 记忆中毒压力测试（注入 10–20% 错误标签，测退化幅度）；
- 跨任务迁移（留出 8 个任务 / leave-one-skill-out）。

**门禁**：只有「计划准确率↑、验证器 ECE↓、记忆中毒退化 <5%、p99 不超预算」同时满足，才允许真机提测。

## 8. UIP-18 · MGD（Memory Guard & Decay）

**五条护栏**：

1. **置信门控写入**：`conf < τ` 不写；低置信结果只进 `M_work`，不进 `M_proc`。
2. **双重验证**：语义验证器 + 几何/规则验证器一致，或连续两帧一致，才写。
3. **来源链与可回滚**：每条记忆带 `ρ`；发现某来源系统性错误时，按来源批量回滚。
4. **新鲜度与域距离**：`h(m)=exp(-λ_age·Δt)·exp(-λ_dom·d_domain)`；域距离大时降权，不直接删除。
5. **漂移检测与冻结**：窗口成功率骤降 / 验证器置信度下降 / 上下文超出覆盖 → 冻结该记忆项，退回任务级先验，重新验证后解冻。

**风险**：护栏过严导致记忆几乎不更新（退化为无记忆）；用离线回放调 `τ`、`λ_age`、`λ_dom`，并监控「记忆命中率 vs 误用率」的权衡。

## 9. 实验设计 E007–E014（离线代理为主，真机前不称「真机结论」）

| 实验 | 对照 | 指标 | 目标 / 证伪线 |
|---|---|---|---|
| E007 | 自动切分 vs 人工标注（抽样子集） | 边界 F1、技能分类准确率 | F1 > 0.8；若 < 0.6 则字母表不可用 |
| E008 | 整任务 VLA vs PMSC（计划级回放） | 计划准确率、步骤分代理、成功率代理 | 步骤分 +20%；若成功率代理下降则回退 |
| E009 | 无记忆 vs 冷启动记忆 vs 在线记忆 | 样本效率、留出任务成功率 | 在线 ≥ 冷启动 ≥ 无记忆；若在线更差则关闭在线 |
| E010 | 无恢复 vs RSP | 恢复成功率、恢复耗时、循环率 | 恢复成功率 > 50%，循环率 < 2% |
| E011 | CRB 预测 vs 实际 | ECE、计划拒绝率 | ECE < 0.1；若拒绝过多则调 `δ` |
| E012 | 无护栏 vs MGD（注入 10–20% 错标签） | 成功率退化、误用率 | 护栏组退化 < 5%；无护栏 > 15% 才值得做 |
| E013 | 无记忆/组合 vs PMSC | p50/p95/p99 延迟、动作 jerk/离群率 | p99 增量 < 30 ms；无异常尖峰 |
| E014 | 留出 8 任务 / leave-one-skill-out | 零样本组合成功率、负迁移率 | 正迁移；若负迁移显著则记忆键需去任务化 |

**消融**：`topk ∈ {1,4,8,16}`、`tau ∈ {0.4,0.6,0.8}`、`p_min ∈ {0.2,0.3,0.5}`、`max_recovery ∈ {0,1,2,3}`、`k ∈ {1,4,8}`、`plan_len ∈ {4,8,12}`。

**证伪优先**：先做 E007/E008/E013。若 E007 切分 F1 < 0.6，或 E013 p99 超预算，则 PMSC 降级为「固定任务模板 + 免训练技能 prompt」，不进入在线记忆阶段。

## 10. 离线回放与记忆评估

1. **数据**：32 个 LeRobot v3.0 数据集；用 UIP-12 切分技能片段；按任务/物体/技能分层切分训练/验证，避免同一 episode 泄漏。
2. **冷启动记忆**：只用训练 split 构建 `M_sem/M_proc`；验证 split 只用于评估，不写入记忆。
3. **在线记忆模拟**：按评测顺序回放验证 split，模拟 `reset()` 与跨 episode 更新；测量「第 1 个 episode vs 第 N 个 episode」的曲线。
4. **中毒压力**：随机翻转 10–20% 的验证器标签，测记忆退化与护栏效果。
5. **5 轴扰动**：位置（图像仿射/裁剪）、背景（前景掩码 + 随机背景）、干扰物（合成粘贴）、未见物品（leave-one-object-out）、人为干扰（人手/手臂叠加）。
6. **指标**：技能边界 F1、技能分类准确率、计划准确率、验证器 P/R/ECE、记忆命中率、步骤分代理、成功率代理、延迟分位数、动作 jerk/离群率。
7. **门禁**：任何改动必须同时满足「计划准确率↑、记忆中毒退化 <5%、p99 不超预算」才允许真机提测。

## 12. 本轮最大风险（承接想法区 §6）

**一句话**：技能切分错误会把不同技能的数据混进同一统计，验证器误判会把错误结果写进长期记忆，二者在跨 episode 复用时会形成自我强化的错误先验；若不做置信门控、双重验证、漂移冻结和离线回放校准，PMSC 会「越用越自信地错」，在 5 条泛化轴上反而比无记忆的整任务策略更差。
