# 第 8 轮（研究线累计；本轮灵感循环第 4 轮）· EMER：把「检索演示」升级为「可写、结果校准、可恢复的情景记忆」

> 检索/复核日期：**2026-10-26（UTC）**。赛事身份不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「深度学习」「多模态融合」「记忆检索」。我先各自钉到本轮核实到的事实上，再合成主判断：**上一轮把「少样本检索（ICR）」当主武器是对的，但 2026-10 出现了直接的反向证据——随机检索也能与各种检索方法打平；因此本轮不是继续调检索键，而是把 ICR 升级为「可写、结果校准、3D 对象中心、可恢复的情景记忆（EMER）」，让策略在测试时真正记住「刚刚发生了什么、哪一步被撤销、上次为什么失败」，并用一个学习到的证据门控决定「信当前策略、信记忆、还是调用恢复」。** 这同时攻人类干扰轴（20% 评测）、终局放置（约 60% 步骤分）和背景/位置 OOD，是比「再换一个更大的 VLA」更便宜、更可证伪的杠杆。

## 0. 本轮先核实：榜单仍是「Live 标签 + 占位数据」，但模型家族是真的

### 0.1 榜单：数字没变，生成方式也没变

`leaderboard.html` 现在标了「Ranking · Live」，但 `leaderboard_data.json` 仍写着 `generated_from: gen_leaderboard.py`；8 个模型 × 32 任务的 256 条记录与上轮完全一致；`details.html` 的 32 段视频全部是「测试视频占位」，`runs.html` 仍是 256/256 占位（[S1][S2][S3][S4]）。所以我**不把 29.7% 当作真实排名**，只把它当「赛事方选择了一组真实模型家族做演示」的信号。任何「榜首方案怎么做」的分析，必须回到这些家族的公开技术报告，而不是这组占位数字。

### 0.2 规则：排名先看成功率，再看步骤分；每任务 10 次、五轴各 2 次

官方参赛手册（[S5][S6]）明确：

- 32 任务，每任务 10 次独立运行；位置/干扰物/背景/未见物品/人为干扰五类各 2 次；单次真机最长 180s，超时失败。
- 排名：先按 32 任务**总平均成功率**，再按**总平均步骤分**，仍相同则提交早者靠前。
- 仅通才单模型赛道；允许 World Model / VLA 等任意架构；但不得混合多个模型。
- 选手自行部署，官方只通过远程 API 调服务；另有**不计分单任务调试**通道。
- 手册公开部分到 2.2「数据资源」为止；外部数据、预训练权重、调试槽次数等条款仍未读到，标「未核实」。

这条规则结构决定了：**人类干扰轴占 20% 的 trial，而它的官方备注大多是「撤销/移动」——这是记忆与恢复问题，不是感知问题。** 上轮只把它当「恢复库」的一个数据源，本轮把它提升为与终局放置并列的第二闸门。

### 0.3 数据：33,276 条、18.28M 帧、169h；四路相机；高位双目有完整标定

本轮实测 32 个 HF 数据集（[S7][S8]）：

- 合计 **33,276 episodes / 18,282,246 帧 / 169.3h**；每任务 969–1,533 条；HangCup 1,043 条 / 194,564 帧 / 30fps。
- 四路视频：`head_stereo_left/right`（已校正立体对）+ `wrist_left/right`；EE 位姿在 base 与 torso 两套坐标；夹爪、下肢、waist 都有。
- **每个数据集的 `meta/info.json` 都带 `camera_params`**：head_stereo 的左右相机矩阵、畸变系数、R/T，且 `rectified: true`；wrist 相机还有 color/IR1/IR2 与 extrinsics。这意味着**不需要外接深度相机，就能从高位双目恢复度量深度**，做 3D 对象中心记忆。
- 每个任务的 `tasks.parquet` 仍是 5 条英文复述用 `@` 连接（本轮复核 HangCup：5 条）[S9]。
- 每个任务的 `info.json` 仍给出 `score_steps` 与 `generalization` 备注；本轮复核 T27/T19/T14：T27 终局「叠碗3」40 分，T19 终局「拉链」50 分，T14 终局「倒药」50 分；human_4 备注分别是「叠了第二个之后拿下第二个」「拉上拉链之后拉开」「拧开盖子之后拧动回来」——**都是 undo 剧本**（[S10][S11][S12]）。

### 0.4 接口：四路 RGB + 本体，没有深度/力觉；但允许时序堆叠与图像缩放

提交模板 v2（[S13][S14]）给出：

- 观测：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 480×640 RGB；双臂 7 维关节、EE 位姿（base）、夹爪开度、lower_body、`observation.language` 单字符串。
- `obs_delta_indices` 决定「传哪些键 + 每键堆叠几帧」；`image_resize` 自定；`action_chunk_size` 自定；动作空间 joint 或 ee 互斥；`reset()` 每 episode 一次。
- **没有深度、没有力/触觉**；所以「多模态融合」只能在 RGB、双目立体、本体、语言、以及我们自己维护的记忆之间做，不能假装有力觉。
- API 侧相机名与数据集侧相机名不同（`cam_left_high` vs `head_stereo_left`），但语义上都是高位左右目；训练时做键名映射即可。映射是否 100% 同一对相机，标「未核实」，需要在调试槽用一帧对齐验证。

### 0.5 任务 JSON 还附了 5 段示例视频，但没有轴标签

T27/T19/T14 的 `info.json` 都有 5 个 `episodes`（episode_0010、0011、0037、0143、0283 等）与 `video_0..4.mp4`（[S10][S11][S12]）。这很可能是任务页「示例」区的 5 段成功演示，不一定对应五类泛化；官方没有给轴标签。**不要把它误当「五轴视频」**；它能做定性检查，但不能替代 `generalization` 字段。

## 1. 榜单头部：八个真实模型家族，一个共同缺口

榜上 8 个名字不是虚构：MolmoAct2、WALL-OSS-0.5、DreamZero、Spirit-v1.5、DM0、PI-0.5、GigaBrain-0、GR00T N1.5 都有公开技术报告/博客。把它们放在一张表里看，路线其实很集中：

| 模型 | 公开路线（本轮核实） | 公开强项 | 在 UniBot 最可能卡住的地方 | 显式情节记忆/恢复？ |
|---|---|---|---|---|
| MolmoAct2 | MolmoER 空间/具身 VLM + flow-matching action expert；3.3M 样本；7 个 benchmark | 空间 grounding、开放权重、低延迟 | 无情节记忆；终局接触/插入；人类 undo 后不知道该步已失效 | 否 |
| WALL-OSS-0.5 | 4B（3B VLM + action expert）；20+ 本体、百万级轨迹；Gradient-Bridged 预训练 | 预训练即可真机执行、15Hz | 无测试时记忆；背景/位置 OOD；失败后无恢复策略 | 否 |
| DreamZero | 14B 视频扩散 WAM；联合预测未来视频与动作；7Hz | 物理动力学、零样本泛化 | 7Hz + 14B 很重；视频预测漂移；记忆是隐式的短窗口 | 隐式、无检索 |
| Spirit-v1.5 | Qwen3-VL-4B + DiT action head；强调数据多样性 | RoboChallenge 真机强 | 无记忆；任务微调后仍怕扰动；恢复弱 | 否 |
| DM0 | 4B VLM + 680M action expert；具身原生预训练 | 操作/导航统一、真机 SOTA 经验 | 长程漂移；人为干扰后无状态回滚 | 否 |
| PI-0.5 | 异构数据 co-training、开放世界泛化 | 语义/环境泛化 | 榜上是 π0.5；π0.6 的 MEM 未上棒；终局放置仍靠策略本身 | 否（π0.6 有 MEM） |
| GigaBrain-0 | 世界模型生成数据 + RGBD + 具身 CoT | 数据 scaling、空间推理 | 无情节记忆；合成数据 gap；系统重 | 否 |

这张表最重要的结论不是「谁强谁弱」（占位数字不可信），而是：**八个头部家族里，没有一个把「显式、可写、结果校准、3D 对象中心的情节记忆 + 失败恢复」作为一等公民。** DreamZero/GigaBrain 有世界模型，但记忆是隐式的、短窗口的；π0.6 有 MEM，但榜上是 π0.5，且 MEM 更偏长程语义记忆，不是 UniBot 这种「人类把刚叠好的碗拿走」的 undo 恢复。**这就是差异化的窗口。**

## 2. 三个灵感词，各自钉到本轮事实上

### 2.1 深度学习：不是「再大一点」，是学习「记什么、何时信」

头部模型已经把「大主干 + 大规模预训练」推到很高；UniBot 的 <30% 说明**继续堆参数/数据的边际收益在下降**（至少在这个评测分布上）。本轮我把「深度学习」落在三个**小得多、但直接决定测试时行为**的学习组件上：

1. **记忆编码器**：把一段 episode 压成固定大小的 token（不是无限增长的 context）。
2. **结果/进度预测头**：判断一条记忆是成功还是失败、当前步骤完成到什么程度。
3. **证据门控**：给定当前观测、检索到的记忆、谓词状态，学习「信策略 / 信记忆 / 调恢复」的权重。

这三个组件可以只有 100–300M，却能改变 4B–14B 主干在 OOD 下的行为。证据：MemBodied 用固定大小情节记忆把无记忆策略的成功率拉到 **7.81×**（LIBERO-Long 90.6%，比 π0 高 5.4pp），且比最强记忆基线少 10× 参数；D²-VLA 在 DOMINO 上 **29.3% vs π0.5 9.6%**、DOMINO-Long **60.0% vs 35.4%**；MemoryVAM 在 LIBERO-Mem 从 **5% 到 42.5%**（[S15][S16][S17][S18]）。这些数字说明：**记忆不是锦上添花，在非马尔可夫任务上是数量级差异。**

### 2.2 多模态融合：API 没有深度，但数据里有标定；做「3D 对象中心」的融合

「多模态融合」最容易被做成「四路 RGB 拼在一起 + proprio 拼接」，这在背景轴一来就过拟合。本轮的做法是：

- **第五模态：双目度量深度**。head_stereo 已校正，`camera_params` 有 K/R/T；用立体匹配得到深度，反投影成 base 系点云。深度不是传感器给的，是我们从数据里「算」出来的，但它是真实几何。
- **融合枢纽是 3D 对象图，不是全局 token**。节点=物体/容器，边=关系（on/in/near/stacked/inserted/open），属性=位姿/尺寸/可操作性/状态。背景只作为点云里的可丢弃平面；位置变化只改变节点坐标；干扰物作为无关节点被门控过滤。
- **腕部 RGB 做局部精修**。高位双目看全局，腕部看接触；用 EE 位姿 + 手眼标定把腕部观测挂到对象节点上。
- **模态 dropout + 视角鲁棒专家**。训练时随机丢一路相机/深度，推理时按可靠性加权；参考 VersaCamVLA 的 scene-token 接口与 WARP-VLA 的腕部视角 MoE（WARP 把 π0.5 在腕部视角扰动下从 39.2% 拉到 78.3%，[S19][S20]）。
- **不假装有力觉**。API 没有力/触觉；接触只能从夹爪开度、EE 运动、对象位移间接推断。任何「力控」都必须标为不可用或代理信号。

一句话：**多模态融合的胜负不在「融合多少路」，而在「融合到什么结构上」。3D 对象图是抗背景/位置 OOD 的结构。**

### 2.3 记忆检索：三种记忆，一个可写寄存器

「记忆检索」在 UniBot 里至少有三层，不能混为一谈：

1. **语义记忆（跨 episode，离线冻结）**：放置位姿、容器相对关系、任务 schema、恢复技能。来自 33k 演示，离线建库，评测时不写。
2. **情节记忆（episode 内，在线可写）**：刚刚做了什么、哪一步完成、哪一步被人类撤销、上次尝试为什么失败。固定大小，每次 `get_action` 后写入；`reset()` 清空。
3. **失败记忆（跨 episode，离线冻结）**：失败状态 + 诊断 + 纠正动作；来自官方 human 备注、合成扰动、仿真分支。用于恢复检索。

本轮的核心创新是把这三层**统一到一个 `MemoryItem` 结构**，并给每条记忆打上**结果标签（success/failure/unknown）+ 进度标签（SSG phase）+ 3D 关系图 + 诊断**。检索不是「找一张最像的图」，而是「找一条在当前 phase、当前关系下，最可能让进度前进的证据」；如果证据不够好，门控可以**选择不信记忆**。

## 3. 反向证据：随机检索也打平，ICR 必须升级

这是本轮最重要的一次「自我打脸」。2026-10-04 的《When Does Retrieval Help?》系统比较了 RICL 框架下的四种检索：图像检索、VLA state 增强、VLA backbone 特征、随机检索。三个发现（[S21]）：

1. **没有一种检索方法在任务成功率上稳定占优**；随机检索也能拿到非平凡成功率。
2. **标准检索质量指标（如最近邻准确率）不能可靠预测下游 VLA 表现**。
3. **来自不同但相关任务的演示可以提供有用的可迁移信息**。

这直接威胁上轮的 ICR：如果只是「用视觉/关系键做 KNN，把动作先验拼进去」，很可能打不过随机检索，或者只是在做「多给几条演示」的正则。**所以本轮必须做三件事：**

- 把检索键从「像不像」改成「**phase + 3D 关系 + 运动特征 + 结果校准**」；
- 把检索值从「动作块」改成「**成功/失败证据 + 纠正动作 + 诊断**」；
- 把「总是使用记忆」改成「**学习一个门控，允许不使用记忆**」；并设**杀死条件**：如果 OCR 在离线下游指标上不能稳定超过随机检索 ≥ 一个 margin，就关掉检索，只保留 SSG+SVL。

这不是退让，而是把上轮的「检索信仰」变成可证伪的组件。

## 4. 新主判断：从「放置闸门」到「放置 + 恢复」双闸门

上轮的主判断是：**终局放置是 32/32 任务的成功闸门、约 60% 步骤分、唯一跨五轴同时起作用的杠杆。** 本轮不推翻它，而是补上它的盲区：

- 终局放置解决「最后一下放得准不准」；
- 情景记忆/恢复解决「**这一步已经做完了，但被人类撤销了 / 上一次失败了，这次要不要换个做法**」。

UniBot 的五轴里，人为干扰轴占 20%，官方备注大量是 undo；多步任务（T16/T17/T31 等 4–5 步）里，任何一步被撤销都会让「当前观测」看起来像「还没做」，但正确的行为是「恢复/重做」，而不是「从头再来」。**一个无记忆的策略无法区分「没做」和「做了又被撤销」；这是结构性的，不是数据量能补的。**

所以本轮的主判断是：

> **UniBot 的下一层瓶颈不是「语义理解」或「抓取」，而是「非马尔可夫状态跟踪 + 失败恢复」。用「3D 对象中心的情节记忆 + 结果校准检索 + 证据门控 + 恢复回路」去攻它，与上轮的终局放置形成双闸门；两者共享同一套 SSG/PGL/SVL，不增加第二个模型。**

### 4.1 为什么是现在：三个条件同时具备

1. **数据条件**：33k 演示 + 四路相机 + 双目标定 + 官方 undo 备注；这是记忆/恢复的天然训练场。
2. **方法条件**：MemBodied/MemoryVLA/D²-VLA/MemoryVAM 证明固定大小情节记忆可行；Retrieve-then-Steer 证明「成功记忆 + 进度校准」可行；Recova/FLARE/RoboRecover/Kintsugi 证明失败恢复可以单独训练和评估。
3. **竞争条件**：头部模型全是 stateless/隐式记忆；π0.6 MEM 未上棒且偏语义记忆。**现在做「3D + 结果校准 + 恢复」是空位。**

### 4.2 为什么不是「换更大的模型」或「上世界模型」

- 换更大模型：DreamZero 14B、GigaBrain 37k 小时数据已经是重资产；我们再堆很难超过，而且不解决 undo。
- 上世界模型：DreamZero/GigaBrain 已经证明世界模型有价值，但 7Hz/重系统不适合 180s 多任务远程评测；本轮把世界模型降为**离线教师**（可选蒸馏），不做运行时视频生成。
- 上测试时 RL/TTT：可能违反「单模型/公平性」且延迟高；本轮默认不做，只做**非参数记忆写入**（episode 内），并在模型卡披露。

## 5. 算术：双闸门的收益分解

设 32×10=320 trials，五轴各 64（20%）。用保守假设：

| 改进 | 作用范围 | 保守增益 | 说明 |
|---|---|---|---|
| 人类干扰轴恢复 +20pp | 20% trials | **+4.0pp** | undo 从「不会恢复」到「恢复一半」 |
| 终局放置 +10pp | 所有轴，q≈0.6 到达终局 | **+6.0pp** | 与上轮相同，但本轮用记忆位姿+SVL |
| 背景/位置 OOD +5pp | 40% trials | **+2.0pp** | 3D 对象图减少外观依赖 |
| 重叠/相关性折扣 | — | **−2~−4pp** | 三项不是独立 |
| **合计（保守）** | — | **+5~7pp** | 目标：30%→35–37% |

这不是保证，而是可证伪的预算：如果调试槽里 T27/T19 的恢复成功率没有 +20pp，或终局步没有 +10pp，就回退到上轮的 PILOT（SSG+PGL+OPT+SVL），不把记忆当主武器。

## 7. 修剪：本轮明确不做什么

- **砍掉「朴素视觉 KNN 检索」**：负结果已经说明它可能只是随机基线；升级为 OCR。
- **砍掉「检索总是有益」的假设**：加杀死条件；门控可以关记忆。
- **砍掉运行时世界模型/视频生成**：延迟与系统复杂度不划算；只保留离线蒸馏（可选）。
- **砍掉力控/触觉**：API 没有；不要用「力」讲故事。
- **砍掉每任务 LoRA/多模型**：单模型合规。
- **砍掉跨 episode 在线写入（计分跑默认）**：避免「测试时适应」公平性争议；episode 内 EMR 足够处理 undo；语义记忆离线冻结。
- **保留但降级**：FLEET 工程检查单、TCLB 离线比较台、全 32 任务高保真孪生。
- **保留并升级**：SSG、PGL、OPT、SVL、NRB、GPR-VLA、TLE/ACP/GF。

## 8. 风险与合规（先立后破）

- **检索负迁移**：OCR 必须打败随机检索；否则关掉。门控要能输出 0。
- **3D 深度失败**：透明/反光物体（试管、药瓶、塑料袋）立体匹配会坏；分桶回退到腕部 RGB + 单目深度/关系先验。
- **记忆污染**：把干扰物/背景写进记忆；对象图只保留任务相关节点，写入前做相关性过滤。
- **undo 检测误判**：谓词噪声；用「谓词 1→0 + 对象位姿变化 + 夹爪状态」多信号 + 迟滞。
- **延迟**：SMR 5–10Hz、OCR <10ms、EAG <5ms；p99 目标 <100ms；超了降频/降 K。
- **单模型审计**：所有学习组件在同一个 checkpoint；记忆库是数据；模型卡披露。
- **外部数据**：默认 OFF；L2L 实验室数据只在邮件确认后开。
- **榜单占位**：不拿 29.7% 做真实基线；用自己的 held-out + 调试槽。

## 9. 一句话押注

**把「记忆」从检索一条演示，升级为「可写、结果校准、3D 对象中心、可恢复的情景记忆 + 证据路由」：它同时攻人类撤销（20% 评测）、终局放置（约 60% 步骤分）和背景/位置 OOD，是当前最值得押注的创新点。**

### 2.2 共同缺口：无记忆、无恢复、无结果校准

把八个家族放在一起，缺口非常一致：

1. **无显式情节记忆**：策略只看当前/短窗口观测；人类把刚完成的步骤撤销后，当前观测与「还没做」几乎一样。
2. **无失败恢复**：训练数据是成功演示；失败状态没有监督；RoboRecover 明确证明「初始状态性能不能决定恢复性能」（[S25]）。
3. **无结果校准检索**：即使做 retrieval，也多是视觉/状态相似度；2026-10 的负结果说明这不够（[S21]）。
4. **终局接触精度**：flow-matching/diffusion 生成平滑 chunk，但最后 1–3cm 的插入/堆叠/闭合仍需要闭环与验证。

**这四条正好对应本轮的四个组件：SMR/EMR、RRL、OCR、SVL。** 头部模型的强项（语义、物理先验、数据规模）不需要重造；我们只在它们之上加一层「测试时记忆与恢复」。

## 3. 主判断与算术

### 3.1 双闸门

```text
成功率 = P(所有步骤完成)                    # 终局步骤是闸门
步骤分 = Σ w_i × P(步骤 i 完成)             # 放置类 ≈59.7%，终局 ≈39.8%
人类干扰轴 = 20% trials                     # 5 类 ×2 / 10 次
```

- **闸门 1（上轮）**：终局放置/插入/闭合。它跨五轴起作用。
- **闸门 2（本轮）**：非马尔可夫状态跟踪 + 恢复。人类撤销后，如果策略不能识别「这一步已经完成又被撤销」，它会把「恢复」误判为「从头做」或「跳过」，直接丢掉该 trial 的成功与步骤分。

### 3.2 收益分解（保守）

| 改进 | 作用范围 | 保守增益 | 说明 |
|---|---|---|---|
| 人类干扰轴恢复 +20pp | 20% trials | +4.0pp | undo 从不会恢复到恢复一半 |
| 终局放置 +10pp | 所有轴，q≈0.6 | +6.0pp | 与上轮重叠，保守按 +3~4pp |
| 背景/位置 +5pp | 40% trials | +2.0pp | 3D 对象图减少外观依赖 |
| 重叠/相关性折扣 | — | −2~−4pp | 三项不独立 |
| **合计** | — | **+5~7pp** | 30%→35–37% 的目标 |

### 3.3 为什么不是「换更大模型」

- DreamZero 14B、GigaBrain 37k 小时、WALL-OSS 百万轨迹：再堆是重资产，且不解决 undo。
- 记忆/恢复是**结构性缺失**，不是数据量问题；一个 100–300M 的记忆适配器可能比再大 2B 的主干更有效。
- 记忆/恢复可以与任何强主干组合；本轮默认 WLA-1.0-Base（Unitree 自家、Apache-2.0、24GB 可微调），也可换 MolmoAct2/WALL-OSS-0.5（需确认预训练权重合规）。

### 3.4 为什么不是「运行时世界模型」

- DreamZero 7Hz、14B；GigaBrain 三系统；远程 API + 180s 多任务评测，运行时视频生成不划算。
- 世界模型的价值可以**离线蒸馏**：Think Like a World Model 用冻结教师特征对齐，0.8B 学生在 LIBERO 97.9%、RoboCasa-GR1 48.2→50.5%，部署 32ms/1.86GB（[S28]）。本轮把 WMD 作为可选增强，不进主路径。

### 4.2 SMR：立体度量记忆（Stereo Metric Reconstructor）

**目标**：把四路 RGB + 本体变成「base 系对象图」，作为抗背景/位置 OOD 的记忆枢纽。

**步骤**：

1. **标定**：从数据集 `camera_params.head_stereo` 读 K_left/K_right、dist、R、T；rectified=true，直接双目匹配。腕部相机用 color K + hand-eye（EE 位姿 + 固定安装）挂到 base。
2. **深度**：rectified 双目 → disparity（RAFT-Stereo / FoundationStereo / SGBM 快速版）→ `Z = f·B/d`；`B=||T||≈58.25mm`，`f≈282px`。输出 base 系点云；桌面平面 RANSAC 去除。
3. **对象分割**：Grounded-SAM/SAM2 + 语言/任务先验；腕部视角做局部补全；透明/反光物体用深度置信度掩码，失败则回退到 2D 框 + 关系先验。
4. **对象图**：节点={物体, 容器, 架, 工具}；边={on, in, near, stacked, inserted, open, closed, held}；属性={6D pose, bbox, size, affordance, state, uncertainty}。
5. **跟踪**：XMem/ByteTrack + 3D 最近邻；被遮挡时保留 last-known pose + 不确定性；人类移动物体时用点云变化检测更新。
6. **Token 化**：object tokens 32 + relation tokens 16 + scene token 8；每 token 带不确定性；背景不进入 token（只作为可丢弃平面）。

**输出**：`G_t`（对象图）、`X_t`（48–56 个 3D/关系 token）、`U_t`（不确定性）。

**为什么不是 2D token**：背景轴换桌布/纹理时，2D token 分布漂移；3D 节点坐标与关系不变。位置轴移动物体时，关系图更新；干扰物作为无关节点被 EAG 过滤。

### 4.3 EMR：情节记忆寄存器（Episodic Memory Register）

**目标**：固定大小、可写、跨 policy call 保留「发生了什么」；解决 undo/长程非马尔可夫。

**Schema**：

```python
MemoryItem = {
  "id": int,
  "task_id": str,
  "episode_id": int,
  "phase": int,                 # SSG 步骤序号
  "t": int,                     # 帧/调用序号
  "graph": G_t,                 # 对象图快照（压缩后）
  "action": a_{t:t+H},          # 执行的动作 chunk
  "outcome": "success"|"failure"|"unknown",
  "diagnosis": {"mode": "P1..P6", "object": str, "container": str},
  "recovery": a_recover|None,   # 纠正动作（离线/在线）
  "embedding": e,               # 压缩 token
  "utility": float              # 学习到的检索效用
}
```

**写/读**：

- `reset()`：清空 EMR；写入 8 token episode anchor（初始场景的对象图 + 任务指令 + 初始位姿）。
- 每次 `get_action`：先读 EMR（当前 phase 的最近 k 条 + anchor），再执行；下一帧根据 SSG 谓词/对象图变化写回 outcome。
- 固定 64 token：Perceiver/Recap 压缩；不随 episode 增长；延迟稳定。
- 成功/失败都写；失败项带诊断，供 OCR/RRL 检索。

**证据**：MemBodied 的 associative state + episode anchor（7.81× stateless；LIBERO-Long 90.6%）；MemoryVLA 的 perceptual-cognitive memory bank；MemoryVAM 的 Recap-Cue（5→42.5%）；D²-VLA 的双记忆/双频 KV cache（DOMINO 29.3 vs 9.6）[S15][S16][S17][S18]。

### 4.4 OCR：结果校准检索（Outcome-Calibrated Retrieval）

**目标**：不是「找最像的演示」，而是「找最可能让当前 phase 前进的证据」；必须打败随机检索。

**键**：

```text
q = [phase_emb; graph_emb(G_t); motion_sig(ΔEE, Δobject, flow); language_emb]
```

- `phase_emb`：SSG 步骤 + 5 条复述的规范化嵌入。
- `graph_emb`：对象/容器相对位姿、关系三元组、夹爪状态；**不用全局外观**。
- `motion_sig`：最近 0.5–1s 的 EE 速度、对象位移、光流统计；区分「没做」与「做了又被撤销」。
- `language_emb`：任务指令/复述；用于跨任务迁移。

**值**：

- 成功证据：成功 segment 的动作先验 + 释放位姿 + 关系结果。
- 失败证据：失败状态 + 诊断 + 纠正动作（来自 NRB/合成失败/仿真分支）。
- 跨任务证据：相关任务的 segment（负结果发现相关任务可迁移；[S21]）。

**效用学习**：

```text
u(q, m) = P(使用 m 后当前 phase 前进 | q, m)
```

- 标签：离线用「检索后执行是否推进 SSG 谓词」；仿真/2.5D 回放可给反事实标签；真实调试槽可给少量在线标签。
- 训练：BCE + pairwise ranking（正/负/随机/hard negative）；hard negatives = 同 phase 错物体、不同 phase 同物体、随机。
- 校准：temperature scaling；EAG 用校准后的 `u`，不用原始相似度。
- **杀死条件**：离线 downstream 指标（恢复成功率/终局步成功率）不能稳定超过随机检索 ≥1 个 margin → 关 OCR。

**为什么能打**：负结果说「随机检索也有非平凡成功率」，说明收益可能来自「多给几条上下文」；OCR 的差异是**结果标签 + phase 对齐 + 3D 关系 + 学习效用**，把「多给」变成「给对」。如果打不过随机，就诚实关掉。

### 4.5 EAG：证据门控（Evidence Authority Gate）

**目标**：允许策略「不信记忆」；在策略/记忆/恢复之间做证据路由。

**输入**：

```text
[policy_conf; u(q,m); predicate_state; consistency(policy, memory); phase; U_t; history_len]
```

**输出**：

```text
w_policy, w_memory, w_recovery ∈ [0,1], sum=1, 可稀疏（w_memory=0）
```

**训练**：

- 主损失：outcome BCE（最终成功/失败）+ phase progress BCE。
- 辅助：gate entropy/sparsity（鼓励必要时才用记忆）；modality dropout（随机丢相机/深度/记忆）；counterfactual gate labels（同一状态，有/无记忆的增益）。
- 校准：ECE / reliability diagram；低置信时回退 policy。
- 推理：`w_recovery > τ_r` 且谓词回归 → RRL；否则 policy+memory 融合。

**与 TEAR 的区别**：TEAR 路由「人遥控 vs 本地自主」；EAG 路由「当前策略 vs 记忆先验 vs 恢复技能」，是内部证据路由，不需要人遥控（[S27]）。

### 4.6 RRL：恢复回路（Recovery Retrieval Loop）

**触发**：

- SSG 谓词从 1→0（已完成步骤被撤销）；或对象位姿变化 > τ（人类移动/拿走）；或 SVL 稳定性校验失败；或连续 N 帧无进度。

**流程**：

```python
def recover(obs, phase):
    # 1) 找撤销前 anchor：EMR 中 phase 最后一次 success 的 graph/action
    anchor = emr.last_success(phase)
    # 2) 找失败记忆：OCR failure memory，同 phase/关系
    fail = ocr.retrieve_failure(graph=smr.graph, phase=phase, k=4)
    # 3) 生成恢复动作：检索纠正动作 / 恢复技能 / 脚本 reset
    a_rec = eag.route_recovery(anchor, fail, obs)
    # 4) 执行 + 校验
    for chunk in a_rec:
        send(chunk)
        if ssg.predicate(phase, obs) and stable(obs, 0.5):
            return True
    # 5) 预算内重试；否则回退任务策略
    return False
```

**恢复技能库**（离线）：

- 重新抓取（regrasp）、重新放置（replace）、推正（nudge）、拉开/拉合（zip）、拧开/拧回（cap）、复位（reset）。
- 来自 NRB 官方备注 + 合成失败 + 仿真分支（Kintsugi 式可恢复性估计；[S26]）。
- 真实调试槽的失败片段可人工标注，加入库（不更新权重）。

**预算**：普通任务 ≤2 次；长程任务（T16/T17/T31）≤1 次；总时长守卫 180s。

### 4.7 与 SSG/PGL/OPT/SVL 的接线

- **SSG**：提供 phase、谓词、终局闸门；EMR/OCR/RRL 都以 phase 为索引。
- **PGL**：槽位/区域→2D 锚点→6D 位姿；3D 目标来自 SMR；锚点渲染进头/腕图像。
- **OPT**：容器系释放位姿统计；作为语义记忆的一种 value；OCR 检索 K 条演示后取稳健中位数；离散度决定伺服/柔顺。
- **SVL**：放置后缓放/静置/稳定性校验；结果写回 EMR；失败触发 RRL。
- **NRB**：官方 undo 剧本 + 合成失败 → EMR/OCR/RRL 的训练数据。
- **GPR-VLA**：唯一学习主干；SMR/EMR/OCR/EAG 的输出作为 token/条件注入；LoRA + memory adapter。

### 4.8 损失

```text
L = L_action
  + λ1 L_outcome        # 成功/失败 BCE
  + λ2 L_progress       # SSG phase 完成 BCE
  + λ3 L_retrieval      # 对比 + utility ranking
  + λ4 L_gate           # outcome BCE + sparsity/entropy
  + λ5 L_recovery       # 恢复动作 flow matching
  + λ6 L_anchor         # episode anchor 重建
  + λ7 L_graph          # 下一帧对象图预测（辅助）
  + λ8 L_consistency    # 策略动作与记忆先验一致性（软）
```

起始权重：λ1=0.2、λ2=0.2、λ3=0.1、λ4=0.1、λ5=0.2、λ6=0.05、λ7=0.05、λ8=0.05；按 held-out 调。

## 5. 数据引擎

### 5.1 从 33k 演示构建记忆库

| 数据 | 做法 | 规模 |
|---|---|---|
| SMR 对象图 | 双目深度 + Grounded-SAM/SAM2 + 跟踪；容器/物体 6D 位姿 | 32 任务 × 200 episodes 抽样 ≈ 6,400 |
| EMR 片段 | 按 SSG phase 切段；每段 1–2s；成功标签 | ≈ 64k segments |
| OCR 池 | 每段压缩 token + phase + 关系 + 运动 + 动作 | ≈ 64k items（可扩到 200k） |
| 放置位姿 H_i | 容器系释放位姿中位数/离散度 | 32 任务 × 步骤 |
| 恢复对 | 官方备注 + 合成失败 + 仿真分支 | 32 任务 × 2 剧本 × 50 ≈ 3,200 |

### 5.2 合成失败（NRB+）

| 类型 | 做法 | 对应官方备注/轴 |
|---|---|---|
| undo | 反向执行最后一段（拿走碗、拉开拉链、拧回瓶盖） | T27/T19/T14/T17 human_4 |
| move | 平移目标/容器（1-DOF） | human_1 多数 |
| drop/offset | 释放时偏移/掉落/弹跳 | 终局放置失败 P4 |
| occlusion | 遮挡目标 0.5–2s | 记忆/遮挡 |
| distractor | 插入无关物体 | 干扰物轴 |
| background | 换桌布/纹理 | 背景轴 |
| unseen | 替换同类不同外观物体 | 未见物品轴 |

合成数据通过 GF（Gap Filter）软权重；真实数据仍主导（合成 ≤30%）。

### 5.3 3D 对象图构建

1. 双目 rectified → disparity → depth → base 点云。
2. 桌面 RANSAC 去平面；聚类 + SAM2 mask → 对象候选。
3. 语言/任务先验选任务相关对象；容器检测（杯架/盒/盘/架）。
4. 6D 位姿：点云 PCA/ICP + 已知物体模型（可选）；透明物体用 bbox + 关系先验。
5. 关系：距离/包含/支撑/堆叠/插入/夹持；规则 + 小分类器。
6. 跟踪：3D 最近邻 + XMem；遮挡保留 last-known + 不确定性。
7. 抽检 10%：对象图关系准确率 <90% 的批次重标。

### 5.4 OCR utility 标签

- 正样本：检索到的 segment 与当前 phase 相同/相关，且执行后 SSG 谓词前进。
- 负样本：同 phase 错物体、不同 phase 同物体、随机、失败记忆。
- 反事实：2.5D 回放/仿真分支给「用 vs 不用」的增益标签。
- 规模：1M query-memory pairs；hard negative 比例 ≥50%。
- 评估：downstream 恢复成功率/终局步成功率，不只看 retrieval accuracy（负结果明确说诊断指标不可靠）。

- AdamW，lr 1e-4（LoRA）/2e-5（全量），cosine，warmup 3%；global batch 64–128；bf16。
- chunk 16–32、horizon 1–2s；早停看真实 held-out + 轴诊断，不看仿真成功率。
- 记忆适配器 100–300M；EMR 64 token；SMR 48–56 token；OCR HNSW。

### 6.3 最小可运行版（单人/小队）

- 冻结一个开源强主干（WALL-OSS-0.5 4B 或 MolmoAct2），不重训。
- 只做：SSG + SMR（双目深度/对象图）+ EMR（规则写入）+ OCR（结果校准 KNN）+ EAG（规则/小 MLP）+ SVL + RRL（脚本恢复）。
- 2–3 周可跑；先验证「记忆/恢复是否真的有增益」，再决定是否训练 adapter。

## 7. 接口工程

### 7.1 观测选择与堆叠

```python
obs_delta_indices = {
  "observation.language": [0],
  "observation.images.cam_left_high":  [-10, -5, 0],   # 短历史看运动
  "observation.images.cam_right_high": [-10, -5, 0],
  "observation.images.cam_left_wrist": [0],
  "observation.images.cam_right_wrist":[0],
  "observation.state.left_arm": [-5, 0],
  "observation.state.right_arm":[-5, 0],
  "observation.state.left_ee_pose_gripper_base": [-5, 0],
  "observation.state.right_ee_pose_gripper_base":[-5, 0],
  "observation.state.left_gripper": [-5, 0],
  "observation.state.right_gripper":[-5, 0],
  "observation.state.lower_body": [0],
}
```

- 长历史交给 EMR，不靠无限堆帧；堆帧只给短运动线索。
- `image_resize`：高位 240×320，腕部 240×320（或 320×480，视延迟）；训练/推理同分辨率。
- `action_chunk_size`：8–16；与 SMR 5–10Hz 解耦；chunk 内不跑重记忆。

### 7.2 动作空间

- 默认 `ee`：放置/插入的位姿级控制更直接；`action.pivot`/gripper 共享。
- 若主干在 joint 上更强，用 joint + 内部 IK 转换；二选一，不混。
- `lower_body`/`pivot`：默认保持/小范围稳定；不把全身控制当研究点。

### 7.3 延迟预算

| 模块 | 频率 | 预算 |
|---|---|---:|
| 双目深度 + 对象图 | 5–10Hz | 30–50ms |
| EMR 写/读 | 每 chunk | <5ms |
| OCR HNSW | 每 chunk | <10ms |
| EAG | 每 chunk | <5ms |
| GPR-VLA | 每 chunk | 50–80ms |
| **p99** | — | **<100ms**（目标） |

超预算：降 SMR 频率到 3–5Hz、K 从 4 降到 2、图像降分辨率、chunk 加大；仍超则关 OCR/EAG，保留 SSG+SVL。

### 7.4 多端口/状态隔离

- 每个评测端口一个服务实例/进程；`reset()` 清 EMR/SMR/轨迹；语义记忆只读共享。
- 健康检查、超时、重连；N 端口并发 soak 4h；p99 延迟与显存监控。
- 不在 `get_action` 里做长时间训练/写盘；记忆写入异步队列。

### 7.5 合规

- **单一 checkpoint**：GPR-VLA + memory adapter + EAG 在一个 checkpoint；SMR/OCR 的确定性代码与记忆库在模型卡披露。
- **episode 内 EMR**：`reset()` 清空；计分跑不做跨 episode 在线写入，避免「测试时适应」公平性争议。
- **语义记忆离线冻结**：来自官方 33k + 合成数据；不随评测更新。
- **外部数据默认 OFF**；L2L 只在邮件确认后开。
- **无测试时权重更新**；无运行时世界模型；无多模型路由。

## 8. 实验设计

### 8.1 假设

- **H1**：UniBot 的人类干扰轴（undo）是无记忆策略的结构性瓶颈；EMR/RRL 能把该轴恢复成功率从 <10% 提到 40–60%。
- **H2**：OCR 的结果校准 + 3D 关系键，在 downstream 上稳定超过随机检索；朴素视觉检索不超过。
- **H3**：EAG 能避免记忆负迁移；在记忆无用的任务上不降，在有 undo/长程的任务上升。
- **H4**：3D 对象图在背景/位置轴上比 2D token 更稳；深度失败时回退不崩。

### 8.2 离线：UniBot-Mem

从 33k 演示构造 5 类历史依赖场景：

| 子集 | 构造 | 指标 |
|---|---|---|
| Undo | 反向执行最后一段（T27/T19/T14/T17） | 恢复成功率、time-to-recover |
| Move | 平移目标/容器 | 重定位后成功率 |
| Occlusion | 遮挡目标 0.5–2s | 记忆检索准确率/下游成功率 |
| Distractor | 插入无关物体 | 干扰物轴成功率 |
| Background | 换桌布/纹理 | 背景轴成功率 |

基线：stateless、短历史、MemoryVLA/MemBodied 风格、Retrieve-then-Steer、随机检索、EMER（消融）。

### 8.3 本地：回放 + 2.5D

- 回放真实 episode，在指定帧注入 undo/move/occlusion；比较有无记忆。
- 2.5D 编辑（换背景/插物体）做轴诊断；不承诺物理高保真。
- 只做失败挖掘与相对比较，不做模型选择（TCLB 降级）。

### 8.4 平台：调试槽

- 每个大版本 1–2 个不计分单任务槽；首选：
  - **T27 StackBowls**：undo「叠了第二个之后拿下第二个」；终局叠碗 40 分。
  - **T19 ZipUp**：undo「拉上拉链之后拉开」；终局 50 分。
  - **T14 PourOutMedicine**：undo「拧开盖子之后拧动回来」；终局 50 分。
  - **T10 PlugCharger**：插头被拔起；插入力/位姿。
  - **T17 OrganizeStationery**：笔盒合上后手动打开；终局闭合。
- A/B：同一任务，stateless vs EMER；分开预约槽；记录成功/步骤分/恢复次数/延迟。
- 判定：T27/T19 恢复成功率 ≥+20pp 且终局步 ≥+10pp，才进计分跑。

### 8.5 计分跑

- 计划 2 次：W7 中期、W8 终期；若只允许 1 次，W8 唯一一次。
- 提交前 4h soak：N 端口、状态隔离、健康检查、p99。
- 记录每任务每步成功率（SSG 步骤级诊断），不只总分。

### 8.6 消融

| 维度 | 设置 |
|---|---|
| 记忆类型 | none / success / failure / both |
| 检索键 | visual / relation / relation+outcome / random |
| 门控 | none / fixed / learned EAG |
| 3D vs 2D | SMR vs 2D token |
| 相机 dropout | 0 / 25 / 50% |
| 记忆大小 | 8 / 16 / 32 / 64 token |
| 恢复预算 | 0 / 1 / 2 |
| 深度 | stereo / monocular / none |
| 跨 episode 记忆 | off（默认）/ on（仅研究） |

### 8.7 统计

- 320 trials；配对 bootstrap 95% CI；报告每轴/每任务。
- 功率：+3pp 约 80%，+5pp 约 90%（p≈0.3，SE≈2.56pp；配对更紧）。
- 调试槽 N 小，只看任务级成功/步骤分与恢复次数，不做过度推断。
- 预注册主指标：总成功率；次指标：步骤分、人类轴恢复率、终局步成功率、p99。

## 9. 创新点清单（持续迭代；动机/差异/可行性/资源/步骤/风险/状态）

> 状态：押注=本轮主线；保留=沿用；升级=旧点改造；降级=保留但非主回路；砍=不做。

### I1 SSG 评分步骤图门控（保留｜核心）
- **动机**：官方 32 任务评分步骤+权重公开；成功=全步骤；防跳步/假完成，并给出「钱丢在哪步」。
- **差异**：现有 VLA 无显式步骤状态；我们不改官方指令，只在内部把指令翻译成步骤图。
- **可行性**：确定性代码 + 学习谓词头；32×5 复述可精确匹配。
- **资源**：无额外数据；CPU；1 人周。
- **步骤**：解析 info.json → 图 → 谓词头（TLE 标签）→ reset 状态机接线。
- **风险**：谓词噪声 → 演示统计校准；语言未覆盖 → 嵌入兜底。

### I2 SMR 立体度量记忆（新增｜押注）
- **动机**：API 无深度，但数据集有 head_stereo 完整标定；3D 对象关系是抗背景/位置 OOD 的最稳记忆键。
- **差异**：已有 memory VLA 多存 2D token；SMR 存 base 系对象图 + 不确定性 + 腕部精修，背景只作可丢弃平面。
- **可行性**：camera_params 齐全；立体匹配/SAM2/跟踪成熟；手眼标定可离线做。
- **资源**：1 张 GPU 做深度/分割；6,400 episodes 建库；3–5 天。
- **步骤**：标定 → 深度 → 分割 → 对象图 → 跟踪 → token 化 → 抽检。
- **风险**：透明/反光失败 → 分桶回退腕部/单目；遮挡 → last-known + 不确定性；标定漂移 → 调试槽对齐。

### I3 EMR 情节记忆寄存器（新增｜押注）
- **动机**：人类 undo 是非马尔可夫；头部模型 stateless；固定大小记忆避免 context 膨胀。
- **差异**：写(phase,图,动作,结果,诊断)，成功/失败都写；episode anchor；不是简单 observation token。
- **可行性**：MemBodied/Recap/MemoryVLA 架构；33k 演示；64 token 固定。
- **资源**：8×H100 1–2 周；1–2 人。
- **步骤**：分段 → 编码 → 写入 → 读取 → reset → 消融。
- **风险**：记忆污染 → 相关性过滤；写入噪声 → outcome 校准；合规 → episode 内、reset 清空。

### I4 OCR 结果校准检索（新增｜押注；替换 ICR）
- **动机**：2026-10 负结果：随机检索也打平；必须做结果校准 + phase/关系键 + 学习 utility。
- **差异**：键=phase+3D关系+运动；值=成功/失败证据+纠正动作；utility 学习；hard negatives；必须打败随机。
- **可行性**：33k 演示 + 合成失败；小预测器；HNSW；离线标签可造。
- **资源**：1M pairs；8×H100 3–5 天。
- **步骤**：建池 → 标签 → 训练 → 校准 → downstream 评估 → 杀死条件。
- **风险**：负迁移 → EAG 置零；标签噪声 → 反事实/仿真；分布漂移 → 在线调试槽少量标注。

### I5 EAG 证据门控（新增｜押注）
- **动机**：记忆可能有害；需要学习「信策略/信记忆/调恢复」，而不是固定拼接。
- **差异**：证据路由（policy/memory/recovery），可置零，校准，模态 dropout；与 TEAR 的人机路由不同。
- **可行性**：小 MLP/Transformer；冻结主干；反事实标签。
- **资源**：8×H100 1–2 周。
- **步骤**：收集 gate 标签 → 训练 → 校准 → 消融 → 延迟。
- **风险**：门控塌缩 → 稀疏/熵正则；过拟合 → dropout/早停；延迟 → 小网络。

### I6 RRL 恢复回路（新增｜押注）
- **动机**：undo/失败后需要恢复；RoboRecover 证明恢复是独立能力；头部模型无恢复策略。
- **差异**：谓词 1→0/对象位移触发；检索撤销前 anchor + 失败记忆；执行/校验/预算；与 EMR/OCR 联动。
- **可行性**：SSG 谓词 + SMR；NRB 脚本；恢复技能可脚本化。
- **资源**：合成失败 3,200 对；2–3 周。
- **步骤**：回归检测 → 恢复库 → 恢复策略 → 校验 → 预算守卫。
- **风险**：误触发 → 多信号+迟滞；恢复循环 → 预算；时间 → 长程限 1 次。

### I7 PGL 放置目标阶梯 + OPT 位姿迁移（保留｜整合）
- **动机**：终局放置是闸门；显式锚点/位姿比 VLM 坐标稳（上轮 AnySlot/Spa-Bench/SpaceVLA 证据）。
- **差异**：本轮把 OPT 的容器系位姿作为语义记忆的一种 value，由 OCR 检索；PGL 的 3D 目标来自 SMR。
- **可行性**：EE 位姿 + 容器检测；K 条演示统计；零梯度。
- **资源**：8×H100 数天建库。
- **步骤**：容器位姿 → H_i 库 → OCR 检索 → 稳健中位数 → 执行/伺服/退化。
- **风险**：透明容器 → 回退锚点伺服；离散度大 → 保守放置。

### I8 SVL 落点闭环（保留｜整合）
- **动机**：终局释放失败（掉落/弹跳/未到位）靠「放完就完」发现不了。
- **差异**：缓放→静置→稳定性/谓词校验→nudge/regrasp/retry；结果写 EMR。
- **可行性**：腕部相机 + 谓词头；180s 预算够 1–2 次。
- **资源**：无新增数据；控制循环。
- **步骤**：稳定性检测 → 修复动作库 → 预算守卫 → 与 SSG/RRL 接线。
- **风险**：耗时 → 长程限 1 次；误判 → 双阈值。

### I9 NRB 官方备注恢复库（保留｜升级）
- **动机**：human_4 备注是 undo 剧本；直接对应评测。
- **差异**：从「自造扰动」升级为「官方剧本回放 + 随机时机 + 合成失败」。
- **可行性**：备注多为 1-DOF 刚体变换；2.5D/仿真可造。
- **资源**：ACP/2.5D 管线；3,200 对。
- **步骤**：备注表 → 场景脚本 → 恢复对 → 加权训练 → RRL 联动。
- **风险**：备注编号含义未核实 → 同时覆盖通用扰动；时机未知 → 随机化。

### I10 MFG 多模态融合（新增｜中优先）
- **动机**：四路 RGB + 双目深度 + 本体 + 语言 + 记忆；视角/遮挡/背景变化需要鲁棒融合。
- **差异**：对象图作为融合枢纽；模态 dropout；视角鲁棒专家；不是全局 token 拼接。
- **可行性**：VersaCamVLA/WARP-VLA 思路；小 adapter。
- **资源**：8×H100 1–2 周。
- **步骤**：模态 dropout → 专家 → 可靠性门控 → 消融。
- **风险**：复杂度/延迟；过拟合；深度失败。

### I11 WMD 世界模型蒸馏（新增｜可选）
- **动机**：世界模型物理先验有价值，但运行时视频生成太重；离线蒸馏可继承。
- **差异**：冻结 DreamZero/GigaBrain 特征缓存，对齐记忆编码器/策略；不做运行时生成。
- **可行性**：Think Like a World Model 已验证（0.8B 学生、32ms/1.86GB）。
- **资源**：教师推理 1–2 天；训练 1 周；显存。
- **步骤**：缓存特征 → 对齐 → 蒸馏 → 评估。
- **风险**：教师域差；许可；算力。

### I12 L2L 产学研数据协议（保留｜中优先）
- **动机**：背景/位置轴本质是场景多样性；实验室网络是最便宜来源。
- **差异**：逐字段对齐的采集协议 + QA + 许可 + 署名。
- **可行性**：高校 G1 保有量/遥操作管线已公开。
- **资源**：3 实验室 ×2 任务 ×100–200 条。
- **步骤**：协议 → 试点 → QA → 合规开关 → 并入。
- **风险**：外部数据规则未明 → 默认 OFF；硬件异构 → 限定 G1+Dex1。

### I13 DebugLoop 平台调试回路（保留｜工程）
- **动机**：真机反馈比自建孪生可信；发布门。
- **差异**：制度化使用不计分单任务槽（预算/任务/判定）。
- **可行性**：profile 页已提供；次数未知。
- **资源**：预约与管理。
- **步骤**：T27→T19→T14/T10；判定表；记录。
- **风险**：槽稀缺 → 每版本 1–2 次；规则变化 → 离线兜底。

### I14 GPR-VLA 主干 + WLA 底座（保留）
- **动机**：单一 checkpoint、可微调、与评分结构对齐。
- **差异**：新增 memory adapter/EAG，但仍是唯一学习主干。
- **可行性**：WLA-1.0-Base 6B、Apache-2.0、24GB 可微调。
- **资源**：8×H100 2–3 周。
- **步骤**：基线 → LoRA → adapter → 联合训练。
- **风险**：底座不够强 → 换 MolmoAct2/WALL-OSS（合规确认）。

### I15 TLE/ACP/GF 数据引擎（保留｜修剪）

- **差异**：本轮只服务记忆/恢复/放置；合成 ≤30%。
- **可行性**：上轮管线；2.5D + 仿真分支。
- **资源**：8×H100 数天。
- **步骤**：相位/谓词标签 → 合成 → GF 权重 → 混采。
- **风险**：负迁移 → GF + 真实主导。

### I16 FLEET 工程检查单（降级｜第 6 轮遗产）

## 10. 风险、合规与开关

| 风险 | 概率 | 影响 | 缓解 | 停止条件 |
|---|---|---|---|---|
| 记忆/恢复假设不成立 | 中 | 高 | 离线 UniBot-Mem + 调试槽 | T27/T19 恢复 <+20pp → 回退 PILOT |
