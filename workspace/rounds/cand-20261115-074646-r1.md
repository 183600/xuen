# 第 70 轮（承接第 69 轮「FLUID-RAS」IP-253~263；灵感循环新循环第 1 轮；本轮灵感：「失败恢复」×「双足机器人」）

> R69 给闭环装上了一张「会提问的嘴」：不确定就去看、去问、去触，把 epistemic 歧义当成一个可以用信息动作消解的题。但整套 FLUID-RAS 有一个从未言明的前提——**你还站在安全集里，而且还有时间问**。双足机器人恰恰活在这个前提的边缘：一次打滑、一次侧推、一步踏空，认证前缀可能瞬间为空；此时 R69 的「任何不确定 → 收紧」会收紧到「零动作」，而在一只脚已经打滑的瞬间，**停住不是安全，停住就是跌倒**。
>
> 本轮两个灵感正好补上这块：
> - **双足机器人**把「失败」从罕见异常变成**连续、混合、欠驱动的日常**：失败不是一个终态，而是一个可以进入、可以管理、可以退出的**混合模式**；安全不是「永不跌倒」，而是「总处在某个已认证吸引子的吸引域内」。
> - **失败恢复**把「恢复」从一句工程口号变成**第二类安全证书**：避障证书回答「这一步是否安全」，恢复证书回答「如果这一步已经不安全，是否还存在一条已认证的路回到安全」。二者是对偶的。
>
> 核心命题：**安全架构要从「单层避障 + 安全停」升级为「安全吸引子阶梯」：可行域 → 恢复域 → 安全跌倒域 → 倒地自起域；每一层都有自己的证书，每一层都必须在 TTF（time-to-failure）内可达下一层。R69 只在第一层内有效；R70 用可恢复性裕度 ρ、失败检测隔离、TTF 与恢复动作证书把保证扩展到阶梯的其余层。** 命名 **PHOENIX-RAS**（Predictive Hybrid Online Emergency recovery with Nested Invariants and eXperience）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「我的测量还准吗」，R69 问「我该向谁求证」，R70 问「**当我救不回来时，怎样输得体面、并且还能站起来**」。

## 0. 直觉与动机

**灵感 1（双足 → 失败是模式，不是终点）**
直觉：轮式机器人「安全停」是一个吸引子；双足机器人「停」往往不是吸引子——单脚支撑、质心越界、接触丢失时，零速度指令会直接把你送出可行域。因此双足的安全架构不能以「停止」为终点，而要以「一组已认证的吸引子」为终点：站立、坐下、跪撑、侧倒护头、倒地后自起。失败恢复因此不是异常处理，而是**常态安全层**：系统任何时刻都要知道自己离最近的吸引子有多远、来不来得及。把「安全停」换成「安全吸引子」，是整个双足安全架构的地基差异。

**灵感 2（失败恢复 → 恢复是避障的对偶证书）**
直觉：R68/R69 的证书都在证明「选中的动作把状态留在安全集内」。但证书是有定义域的：一旦状态已经出了安全集，避障证书不是「失败」，而是**无定义**。恢复证书证明的是另一件事——「存在一个恢复策略，在 T 内把状态带回安全集，且途中不进入灾难集」。一个是前向不变（forward invariant），一个是可达-避撞（reach-avoid）。**把「无定义」误当成「不安全」、再误当成「停住」，正是 R69 在双足上最危险的盲点。** 恢复不是避障的下位补丁，而是同一安全目标的另一半。

**灵感 3（保守性反转 → 越靠近失败，越不能只收紧）**
直觉：R68/R69 的单调铁律是「越不确定越慢越小」。这在可行域内部成立：慢一点、幅度小一点，确实更安全。但在可行域边界外，导数会翻转：刹车与犹豫会缩小可达集、消耗 TTF，**此时「更保守」等于「更快失败」**。所以 R70 必须引入一个相位开关：ρ 大时沿用 R69 的保守；ρ 小时切换为「已认证的果断恢复」——恢复动作可以很大、很快，只要它带证书。这是本轮最重要的理论姿态：**保守不是标量，而是分段的；在边界上，正确的保守是果断。** 这套阶梯不只适用于物理模式，也适用于算法栈本身：标定失效 → 退 R68；WM 失效 → 认证保持；保持不可行（双足）→ 安全吸引子；吸引子不可达 → 安全跌倒。**失败恢复是贯穿硬件与软件的同一条阶梯。**

**灵感 4（TTF → 恢复是一个时间预算问题，而不是一个优化问题）**
直觉：跌倒不给你收敛的时间。检测延迟 t_det、隔离延迟 t_iso、承诺延迟 t_com、动作执行 t_man 必须满足 t_det+t_iso+t_com+t_man < TTF，否则再好的恢复策略也用不上。于是 R69 的「问」被 TTF 严格门控：**只有 TTF > t_ask+t_react 时才允许交互**；TTF 一旦进入承诺窗口，系统必须停止求知、开始执行——用对歧义集鲁棒的恢复策略，而不是继续消歧。这把「求知」与「求生」放进了同一个时间预算，也给出了一条清晰的分工：**求生比求知快**。

**灵感 5（恢复是双刃剑 → 假恢复本身就是一种失败）**
直觉：R69 的交互会「问错」；R70 的恢复会「救错」。一个误报的失败检测加一个被高估的可恢复性，会让系统在本来能站住的时候执行一个激进的恢复动作，把「本可避免的扰动」升级成「自己造成的跌倒」。**「狼来了」在双足上是物理的**：频繁的假恢复会训练出一个不信任自己传感器的控制器，也会耗尽恢复预算。所以本轮必须同时交付：失败宣告纪律（多通道佐证 vs 截止期单通道）、恢复证书的保守校准、假恢复成本与漏检成本的联合阈值，以及恢复动作的混合模式无抖振保证。否则 R70 不是进步，而是给 R69 的保守主义装了一双「会自己绊倒自己」的腿。

## 1. 形式化定义（增量：定义 310–326）

**定义 310（PHOENIX-RAS 总览）** PHOENIX-RAS = (VKM, FDI, TTF, RPL, RAC, RAO, SFM, SRL, FME, RAS-WM‡)。三不变式：
(i) **实时流零学习写操作**（继承 R68 定义 276-i；FME 只离线写）；
(ii) **恢复预算与承诺纪律**：任一时刻至多一个已承诺恢复模式；承诺后设 dwell time，禁止在承诺窗口内反复横跳；
(iii) **双层证书纪律**：常规动作需避障证书（R69 的 C-RAS-WM）；恢复动作需恢复证书（定义 316）；无证书的动作一律不执行，宁可进入安全跌倒。

**定义 311（混合失败模型）** 双足系统建模为混合自动机 H = (Q, X, U, F, G, R)，Q 为接触模式（双支撑 / 左单 / 右单 / 飞行 / 倒地），X 为质心-角动量状态，F_q 为连续流，G 为守卫（打滑 / 触地 / 越界），R 为重置。失败 = 进入「非期望模式」或「可行域外状态」的事件集合 ℱ = {slip, trip, push, actuator_sat, contact_loss, sensor_fault}。失败类型 f 是 ℱ 上的随机变量。

**定义 312（可行核与可恢复性裕度）** 可行核 K = {s : ∃π, ∀w∈W, s(t)∈S_safe, ∀t≥0}（扰动集 W 下受控不变集的近似）。可恢复性裕度 ρ(s) = V_rec(s) − V_safe，其中 V_rec(s) = max_π P(∃t≤T: s(t)∈K ∧ s(0..t)∩C_cat=∅ | s, π) 为可达-避撞值，C_cat 为灾难集（撞人、硬件损毁、头部冲击超限）。ρ>0 在吸引域内；ρ≤0 需恢复或安全跌倒。

**定义 313（失败检测与隔离 FDI）** 观测通道 c = (c_contact, c_res, c_flow, c_imu)，分别来自接触异常、R68 残差、R69 流似然 Δa、IMU 冲击。FDI 输出失败类型后验 p(f|o) 与「已宣告失败」布尔量 d_t。**宣告纪律**：d_t = 1 ⇔ 至少两个正交通道超阈，或 TTF < τ_deadline 且至少一个通道超阈（截止期降级）。注意 R69 的 Δa 在这里从「缓变故障第二意见」升级为「早期失败前兆」。

**定义 314（TTF）** TTF(s) = inf{t : 在最优恢复策略下仍无法避免进入 C_cat 或离开 K 的时间}；实现为学习到的保守分位数 TTF_α(s)（α 取 5% 分位），并显式扣除检测 / 隔离 / 承诺延迟预算。**交互门控**：仅当 TTF > t_ask + t_react 时允许 R69 的 MINT 发起信息动作；进入承诺窗口后交互通道关闭。

**定义 315（恢复策略库 RPL）** 一组参数化混合恢复机动 π_r ∈ Π_rec：踝策略、髋策略、跨步 / 落脚点重规划、下蹲降质心、安全跌倒、倒地自起。每个 π_r 带一个已认证吸引域 A_r 与一个模式序列（接触调度），并满足 R69 的信息动作安全认证（若恢复中包含注视 / 求援）。

**定义 316（恢复动作证书 RAC）** 对状态 s 与恢复策略 π_r，证书 rac(s, π_r) = (p_safe, T_reach, C_avoid, ver) 断言：在扰动集 W 与失败类型歧义集 ℳ 下，π_r 在 T_reach 内以概率 ≥ p_safe 把状态带回 K，且以概率 ≥ 1−ε_r 不进入 C_cat。Valid ⇔ p_safe ≥ p_min ∧ T_reach ≤ TTF_α(s) ∧ 模式序列无 Zeno。**RAC 是避障证书在「失败已发生」域上的对偶。**

**定义 317（恢复感知覆盖 RAO 与安全吸引子阶梯）** 四相位决策：
- P0 可行（ρ>ρ_safe ∧ ¬d_t）：完全等价 R69；
- P1 预警（0<ρ≤ρ_safe）：R69 + 恢复预备（预计算 RAC、预置落脚点、收紧 λ 但保留恢复动作空间）；
- P2 恢复（ρ≤0 ∨ d_t，且 TTF>τ_commit）：承诺 argmin_{π_r} 最坏灾难风险的已认证恢复；
- P3 安全跌倒（无可用 RAC ∨ TTF≤τ_commit）：SFM 执行已认证安全跌倒。
阶梯 = K → 恢复域 → 安全跌倒域 → 自起域，每一层必须在 TTF 内可达下一层。

**定义 318（安全跌倒管理器 SFM）** 在不可恢复时选择受控跌倒轨迹：护头、避人、降低峰值冲击、选择柔顺着地。证书 fall_cert = (head_accel_max, impact_energy, human_clearance, ver)，断言峰值冲击 ≤ a_head 且与人保持 ≥ d_human。安全跌倒不是「放弃」，而是一个有证书的模式。

**定义 319（倒地自起 SRL）** 从倒地状态 s_fall 出发，选择已认证自起策略回到 K；自起本身是新的恢复问题（可能失败），故需自起证书与二次安全跌倒兜底。若自起连续失败 k 次，升级为「求援」信息动作（R69 的 g_ask），此时 TTF 充裕——这是失败恢复与主动交互唯一不冲突的接缝。

**定义 320（失败记忆与离线蒸馏 FME）** 记录失败 / 近失事件 e = (s, f, π_r, outcome, RAC 残差) 到 EpisodeBuf；离线蒸馏更新 VKM / TTF / 恢复策略，经 RAC 复核后才可部署。**在线只读、离线只写**，继承零实时学习写操作。

**定义 321（恢复歧义集与鲁棒恢复 RDA）** 当失败类型不可完全隔离时，保留歧义集 ℳ = {f : p(f|o) ≥ ε_m}。恢复选择不是对 MAP 失败类型最优，而是 min_{π_r} max_{f∈ℳ} Risk(π_r, f)，s.t. RAC 对所有 f∈ℳ 成立。TTF 不足时不做消歧，直接鲁棒化——这是 R69「先问再做」在时间压力下的对偶：**来不及问，就为所有可能答案做准备。**

**定义 322（失败宣告的假阳性成本 FDD）** 定义假恢复成本 c_fp（本可站住却被自己救倒）与漏检成本 c_fn（该救没救）。宣告阈值 τ_d 由 min_τ [c_fp·P(FP|τ) + c_fn·P(FN|τ)] 决定，且受 TTF 约束；**假阳性不是免费的**，它消耗恢复预算并可能直接导致跌倒。

**定义 323（恢复期权价值 VoR）** 把「拥有一个可用恢复机动」视为一份期权：VoR(s) = E[Loss_avoided | 有恢复] − E[Loss | 无恢复] − c_prepare。P1 相位的预备动作（预计算 RAC、预置落脚点）只有在 VoR > 0 时才值得做；这是 R69 的 VoI 在失败域的镜像。

**定义 324（对抗失败集 AIC-PHOENIX）** ℰ_PHOENIX = ℰ_FLUID × ℰ_fail，其中 ℰ_fail 含最坏推搡、打滑、地形落差、执行器饱和 / 失效、传感器故障，以及**恢复陷阱**（看似安全、实则把系统引入更差吸引子的恢复诱导）。并入 AIC。

**定义 325（证书 J_PHOENIX）** J_PHOENIX = (J_FLUID, ρ, TTF_α, failure_type, declaration_votes, recovery_policy_id, rac_prob, T_reach, fall_severity, phoenix_ver)。Valid ⇔ Valid(J_FLUID) ∧（P0 时避障证书有效 ∨ P2 时 RAC 有效 ∨ P3 时 fall_cert 有效）∧ 承诺纪律满足。

**定义 326（TTF 门控的交互与 R69 的严格嵌入）** R69 的 MINT 只在 TTF > t_ask+t_react 时可调用；当 ρ>ρ_safe 且 ¬d_t 且 TTF 充裕时，PHOENIX 与 R69 逐指令相同。故 R69 = PHOENIX 在「永不失败、永远来得及问」边界上的退化；PHOENIX 不削弱 R69，而是在 R69 证书无定义的区域**扩展**了保证域。

## 2. 关键算法骨架

```python
# IP-264 VKM：可恢复性裕度（学习到的可达-避撞值，取保守分位）
def recoverability_margin(vkm, s):
    return vkm.value(s) - V_SAFE          # ρ>0 在吸引域内；ρ≤0 需恢复/跌倒

# IP-265 FDD/FDI：多通道失败宣告（截止期可降级为单通道）
def declare_failure(ch, ttf):
    votes = sum(c > TAU[c_id] for c_id, c in ch.items())
    if ttf < TAU_DEADLINE:                # 来不及佐证，允许单通道
        return votes >= 1, votes
    return votes >= 2, votes               # 常规需两正交通道一致（抗 cry-wolf）

# IP-267/268/273：歧义集下选「最坏情况最优」的已认证恢复
def select_recovery(s, M_amb, library, ttf):
    best = None
    for pi in library:
        if not rac.certify(pi, s, M_amb, ttf):   # 对所有 f∈M_amb 成立
            continue
        worst = max(catastrophe_risk(pi, s, f) for f in M_amb)
        if best is None or worst < best.worst:
            best = RecoveryChoice(pi, worst)
    return best                                # None ⇒ 进入安全跌倒

# IP-270 安全跌倒：不可恢复时也要有证书
def safe_fall(s):
    pi = sfm.plan(s, avoid_humans=True, head_accel_max=A_HEAD)
    return pi if sfm.certify(pi, s) else sfm.most_compliant(s)

# IP-272 FME：失败记忆离线蒸馏（在线只读）
def distill_failures(buf, vkm, ttf, rpl):
    for e in buf.sample():                       # 失败 / 近失事件
        vkm.update(e.s, e.outcome)               # 校准可恢复性
        ttf.update(e.s, e.ttf_true)
        rpl.add_if_better(e, certify=rac.certify)  # 只有过证书才入库
    return vkm, ttf, rpl

# IP-277 主闭环（P0 段与 R69 逐指令相同）
def PHOENIX_RAS_round(M, obs):
    z, o = M.mtm.forward(...)                     # 复用 R68/R69
    rho  = M.vkm.margin(M.state)                  # IP-264
    ttf  = M.ttf.quantile(M.state, alpha=0.05)    # IP-266，已扣延迟预算
    d, v = M.fdi.declare(M.channels(z, o), ttf)   # IP-265
    # ---- P0：可行域内，完全等价 R69 ----
    if rho > RHO_SAFE and not d:
        return R69_step(M, obs)                   # 逐指令相同（定义 326）
    # ---- P1：预警，预备恢复但不打断 R69 ----
    if rho > 0 and not d:
        M.plan.prefetch_recovery(M.state)         # 预计算 RAC / 落脚点
        k, lam, mode = R69_step(M, obs, lam_cap=PREPARE_CAP)
        return k, lam, mode
    # ---- P2：恢复（停止求知，承诺已认证恢复） ----
    if ttf > TAU_COMMIT:
        choice = M.rpl.select(M.state, M.fdi.ambiguity(), ttf)
        if choice is not None:
            M.audit.log_commit(choice, v)         # 承诺纪律 + 审计
            return M.rpl.execute(choice)          # 混合模式，dwell time 锁定
    # ---- P3：安全跌倒（有证书的失败） ----
    return M.sfm.execute(M.sfm.plan(M.state))
```

## 3. 推导

**引理 19（保守性反转）** 设 ρ(s) 为可恢复性裕度，λ 为 R68/R69 的风险缩放（λ↓ = 更保守）。在 A99（VKM 保守估计）下存在边界 ρ=0，使：ρ>0 时 ∂Risk_cat/∂λ > 0（更保守更安全）；ρ<0 时 ∂Risk_cat/∂λ < 0（更保守更危险）。直觉：可行域内缩小动作降低越界概率；可行域外，缩小动作缩小可达集、缩短 TTF，使恢复策略不可行。系：**单一单调 λ 不能覆盖整个状态空间**；R70 的相位开关是必要的，不是工程补丁。

**引理 20（恢复时间预算）** T_rec = t_det + t_iso + t_com + t_man。若 T_rec ≥ TTF_α(s)，则任何恢复策略的成功概率 ≤ P(TTF < T_rec) ≤ α；故此时最优决策是 P3 安全跌倒而非 P2 恢复。系：**恢复不是「选最好的策略」，而是「先问来不来得及」**。

**引理 21（歧义下的鲁棒恢复遗憾）** 设真实失败类型 f*∈ℳ，π_MAP 对 MAP 最优，π_rob 为最坏情况最优。则 Risk(π_rob, f*) − Risk(π_MAP, f*) ≤ 2·diam(ℳ)·L_risk（A100：风险对失败类型 Lipschitz）。当 TTF ≤ t_iso（来不及隔离）时，π_rob 的期望风险 ≤ π_MAP 的期望风险。系：**来不及问，就为所有答案准备**；这与 R69「问后再做」在时间充裕时对偶。

**引理 22（假恢复-漏检权衡）** 设假阳性率 p_fp(τ) 与漏检率 p_fn(τ) 随阈值 τ 单调反向。总期望损失 L(τ) = c_fp·p_fp(τ) + c_fn·p_fn(τ)。最优阈值满足 c_fp·p'_fp = −c_fn·p'_fn。若 c_fp 被低估（忽视「自己救倒自己」），τ 过低，系统进入「狼来了」区：假恢复频率上升，恢复预算耗尽。系：**失败宣告阈值必须显式计入假阳性成本，且由 TTF 动态调制**。

**定理 18（三层安全阶梯 / 双证书）** 在 A99–A102 下：若 P0 的避障证书有效，则灾难概率 ≤ ε_0；若 P0 失效但 P2 的 RAC 有效，则灾难概率 ≤ ε_r + P(T_rec ≥ TTF)；若二者皆失效但 P3 的 fall_cert 有效，则冲击严重度 ≤ 证书界且人道安全距离满足。故闭环灾难概率 ≤ max(ε_0, ε_r + α, ε_fall)。**安全不再是单点断言，而是一条阶梯，每层都有界。**

**定理 19（域扩展而非削弱）** 在 R69 证书有定义的域 D_R69 = {s : ρ(s)>ρ_safe ∧ TTF>horizon ∧ ¬d_t} 上，PHOENIX 与 R69 逐指令相同；在 D_R69 外，R69 的保证为空（其假设不成立），而 PHOENIX 由定理 18 给出非空保证。故 PHOENIX 的保证域严格包含 D_R69，且在 D_R69 上不降低任何安全性。**这是对 R69「任何不确定 → 收紧」最诚实的修补：不是推翻它，而是指出它的定义域，并在域外接管。**

**定理 20（混合切换无抖振与无危险瞬态）** 承诺纪律（至多一个恢复模式、dwell time、迟滞 h）使 P0↔P1↔P2↔P3 的切换构成无 Zeno 的混合自动机；每个切换守卫要求目标模式证书在当前状态有效，且切换瞬间控制量满足有界 jerk 约束（A101）。故闭环无抖振、无因模式切换导致的失稳。**恢复的安全性不仅取决于策略，还取决于「什么时候切换」。**

**定理 21（离线恢复学习不破坏实时安全）** FME 只在离线写；在线只读已认证库；RAC 对分布外状态返回空集 ⇒ 自动降级 P3；恢复策略更新须经 RAC 复核（A102）。故学习不改变在线可证明界，只扩大未来可用库。**失败经验可以学，但不能在跌倒的 200ms 里学。**

## 6. 本轮最大风险

**一句话**：PHOENIX-RAS 的全部安全性押在「可恢复性是可估的」这一前提上——**VKM/TTF 一旦高估可恢复性（以为还能救、其实已经救不回），系统就会在最危险的时刻用「恢复」覆盖 R69 的保守，把一次本可站住的扰动变成一次真实跌倒；救错，比不救更致命。**

**次级风险与缓解**：
1. **假失败宣告（cry-wolf）**：误救自己把自己绊倒 → FDD 双通道佐证 + 假阳性成本入阈值 + E309；
2. **TTF 高估**：承诺太晚，恢复来不及 → TTF_α 保守分位 + 引理 20 时间预算硬约束 + P3 兜底；
3. **恢复陷阱**：看似安全、实则引入更差吸引子 → ℰ_fail 对抗训练 + RAC 对歧义集全成员认证 + E315；
4. **模式切换抖振**：P0↔P2 反复横跳 → dwell time + 迟滞 + 无 Zeno 证明（定理 20）；
5. **sim-to-real 接触差**：恢复策略在真机失效 → 域随机化 + RAC 保守校准 + 迁移不达标即退回安全跌倒。

## 3. 关键算法伪代码

```python
# IP-264 VKM：可恢复性裕度
def recoverability_margin(vkm, s):
    return vkm.value(s) - V_SAFE          # ρ>0 在吸引域内；ρ≤0 需恢复/跌倒

# IP-265/274 FDI+FDD：多通道宣告，截止期可降级单通道
def declare_failure(ch, ttf):
    votes = sum(c > TAU[c_id] for c_id, c in ch.items())
    if ttf < TAU_DEADLINE: return votes >= 1, votes
    return votes >= 2, votes               # 常规需两正交通道一致（抗 cry-wolf）

# IP-267/268/273：歧义集下选最坏情况最优的已认证恢复
def select_recovery(s, M_amb, library, ttf):
    best = None
    for pi in library:
        if not rac.certify(pi, s, M_amb, ttf): continue   # 对所有 f∈M_amb 成立
        worst = max(catastrophe_risk(pi, s, f) for f in M_amb)
        if best is None or worst < best.worst: best = RecoveryChoice(pi, worst)
    return best                                # None ⇒ 安全跌倒

# IP-270 安全跌倒：不可恢复时也要有证书
def safe_fall(s):
    pi = sfm.plan(s, avoid_humans=True, head_accel_max=A_HEAD)
    return pi if sfm.certify(pi, s) else sfm.most_compliant(s)

# IP-277 主闭环（P0 段与 R69 逐指令相同）
def PHOENIX_RAS_round(M, obs):
    z, o = M.mtm.forward(...)
    rho  = M.vkm.margin(M.state)                  # IP-264
    ttf  = M.ttf.quantile(M.state, alpha=0.05)    # IP-266，已扣延迟预算
    d, v = M.fdi.declare(M.channels(z, o), ttf)   # IP-265
    if rho > RHO_SAFE and not d:                  # P0：完全等价 R69
        return R69_step(M, obs)
    if rho > 0 and not d:                         # P1：预警 + 恢复预备
        M.plan.prefetch_recovery(M.state)
        return R69_step(M, obs, lam_cap=PREPARE_CAP)
    if ttf > TAU_COMMIT:                          # P2：停止求知，承诺恢复
        choice = M.rpl.select(M.state, M.fdi.ambiguity(), ttf)
        if choice is not None:
            M.audit.log_commit(choice, v)
            return M.rpl.execute(choice)          # dwell time 锁定
    return M.sfm.execute(M.sfm.plan(M.state))     # P3：有证书的安全跌倒
```

## 4. 推导

**引理 19（保守性反转）** 设 ρ 为可恢复性裕度、λ 为风险缩放（λ↓ 更保守）。在 A99 下存在边界 ρ=0：ρ>0 时 ∂Risk/∂λ > 0（更保守更安全）；ρ<0 时 ∂Risk/∂λ < 0（更保守更危险）。系：单一单调 λ 无法覆盖全状态空间，相位开关是必要的。

**引理 20（恢复时间预算）** T_rec = t_det+t_iso+t_com+t_man ≥ TTF_α ⇒ 任何恢复成功概率 ≤ α，此时最优是安全跌倒而非恢复。系：恢复先问「来不来得及」。

**引理 21（歧义下鲁棒恢复遗憾）** 真实 f*∈ℳ 时，Risk(π_rob,f*) − Risk(π_MAP,f*) ≤ 2·diam(ℳ)·L_risk；TTF ≤ t_iso 时 π_rob 期望风险 ≤ π_MAP。系：来不及问，就为所有答案准备。

**引理 22（假恢复-漏检权衡）** L(τ)=c_fp·p_fp(τ)+c_fn·p_fn(τ)，最优满足 c_fp·p'_fp = −c_fn·p'_fn；低估 c_fp 会进入「狼来了」区并耗尽恢复预算。

**定理 18（三层安全阶梯 / 双证书）** P0 避障证书 ⇒ 灾难 ≤ ε_0；P2 RAC ⇒ 灾难 ≤ ε_r + P(T_rec ≥ TTF)；P3 fall_cert ⇒ 冲击 ≤ 证书界且满足人身距离。故闭环灾难 ≤ max(ε_0, ε_r+α, ε_fall)。

**定理 19（域扩展而非削弱）** 在 D_R69 上 PHOENIX 与 R69 逐指令相同；域外 R69 保证为空，PHOENIX 由定理 18 给出非空保证。故保证域严格扩展，域内安全性不降。

**定理 20（无抖振与无危险瞬态）** 承诺纪律（单模式 + dwell time + 迟滞）使四相位切换构成无 Zeno 混合自动机；切换守卫要求目标证书有效且有界 jerk，故无抖振、无切换失稳。

**定理 21（离线学习不破坏实时安全）** FME 只离线写、在线只读；RAC 对 OOD 返回空集即降级 P3；更新须过 RAC 复核，故学习只扩大未来可用库，不改变在线可证明界。

## 7. 本轮最大风险

**一句话**：PHOENIX-RAS 的全部安全性押在「可恢复性是可估的」这一前提上——**VKM/TTF 一旦高估可恢复性（以为还能救、其实已经救不回），系统就会在最危险的时刻用「恢复」覆盖 R69 的保守，把一次本可站住的扰动变成一次真实跌倒；救错，比不救更致命。**

**次级风险与缓解**：假失败宣告（FDD 双通道 + 假阳性成本入阈值 + E309）；TTF 高估（保守分位 + 引理 20 时间预算 + P3 兜底）；恢复陷阱（ℰ_fail 对抗训练 + RAC 全歧义集认证 + E315）；模式切换抖振（dwell time + 迟滞 + 定理 20）；sim-to-real 接触差（域随机化 + 保守 RAC + 不达标退回安全跌倒）。
