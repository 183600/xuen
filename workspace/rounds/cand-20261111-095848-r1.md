# 第 55 轮（承接第 54 轮 v31 GroundEdge-GenSim+++；灵感循环第 6 轮；本轮灵感：「传感器融合」×「角色一致性」）

> 第 54 轮把技能组合推进到动作空间剖面 `α_S`、技能组合图 SCOM 与云边联合证书 `J=(ρ,A_cert,γ_ce,δ_a)`。本轮引入两个更底层的新视角：**传感器融合不是异质证据的平均，而是角色化证据的受约束裁决**；**角色一致性是证书在传感器替换、云边交接与 sim-to-real 迁移时被长期忽略的隐性前提**。核心矛盾：
> - **H24**：多模态融合普遍采用固定权重或协方差交叉，默认各传感器“永久可信、角色不变”；一旦传感器换位、延迟反转或云边交接，融合输出仍然平滑合理，但语义已经错位。
> - **H25**：已有证书 `J` 是在某个**隐含角色分配 π** 下签发的；π 发生漂移时，证书可以“静默失效”——签名时 RGB 是语义角色、力觉是接触角色，运行时二者在流水线里被对调，证书却仍显示 valid。

## 0. 直觉与动机

**灵感 1（从“融合证据”到“角色契约”）**
直觉：RGB 负责语义、深度负责几何、IMU 负责高频运动、力/触觉负责接触、本体感知负责关节状态——它们不是同质证据，而是各司其职的“角色”。融合前应先问：这个传感器此刻是否在履行它被认证的角色？它有没有越界回答不属于它的问题？把传感器建模为 `(角色 r, 视角 φ_r, 能力域 C_r, 延迟 τ_r, 不确定度 u_r)`，融合就从加权平均变成 **在角色能力域内做受约束裁决**。角色不是标签，而是“谁有资格对 Q 的哪一部分作出承诺”的契约。

**灵感 2（任务相关商空间 Q：一致性必须落在任务真正关心的量上）**
直觉：RGB 的“杯子在左”与深度的“杯子在左 3cm”在像素空间永远对不齐，但在任务商空间 `Q`（物体位姿、抓取点、接触力旋量、关节状态）上可以比较。角色一致性不应是原始观测一致，而应是 **经各角色视角投影到 Q 后的一致**。`Q` 选错会让一致性要么空洞（维度太低，什么都一致），要么苛刻（维度太高，永远不一致）。因此 `Q` 本身必须由任务动作集合 `A_T` 决定，并与第 54 轮的 `α_S` 对齐：`Q` 只保留“动作会读取或改变的量”。

**灵感 3（一致 ≠ 正确：必须保留角色无关锚点）**
直觉：五个传感器可能因共同标定偏差、共同坐标系错位或同源仿真误差而“一致地错”。角色一致性只能排除**互相矛盾**，不能排除**共同偏差**。因此系统必须保留至少一个 **角色无关的物理锚点**（标定板、外部计量、已知重力方向、接触探针、已知尺寸量块），用它锚定 `Q` 的原点与尺度；否则我们只是把“共识错误”认证成“可信真值”。这是本方案与普通多传感器融合最根本的分界线。

**灵感 4（角色漂移与角色别名：静默失效的两种形态）**
直觉：角色漂移是缓慢的（标定老化、镜头污损、坐标系蠕变）；角色别名是突发的（IMU 被误接入力通道、深度与 RGB 外参接反、云边模块顶替）。二者共同特征是：输出仍然“看起来合理”，残差可能还很小，但角色语义已错。需要 **角色挑战探针**：执行只改变某一模态预期签名的微动作（轻触、微移、遮挡、加载），用跨角色响应模式来消歧，而不是等任务失败后再回溯。探针的收益是信息增益，代价是扰动量与时间，与第 54 轮“认知动作”属于同一预算体系。

**灵感 5（角色一致性作为可迁移不变量 → 证书账本）**
直觉：把第 53 轮 `ρ`、第 54 轮 `J` 的签发前提显式化为角色分配 `π` 与角色一致性证书 `K_R`，形成 **角色一致性账本 `L_R`**：记录谁在何时以何角色签发了什么 claim、如何被裁决、何时过期。跨云边、跨传感器替换、跨 sim-real 迁移时，先迁移账本与 `K_R`，再迁移 `ρ` 与 `A_cert`；账本不一致则证书降级为“仅观察、不承诺”。这把“传感器融合”从运行时算子提升为贯穿证书生命周期的治理机制。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（角色化传感模式 RTS）**
角色化传感模式 `ℛ = (R, S, Π, Φ, C, U, Q, q)`：
- `R = {r_1,…,r_m}` 为有限功能角色集（如 `r_sem, r_geo, r_mot, r_con, r_prop`）；
- `S` 为传感器集，`Π : S → 2^R` 为传感器到角色的分配（一个传感器可兼多角色，一个角色可由多传感器冗余填充）；
- `Q` 为任务相关商空间，`Φ = {φ_r : O_{S_r} → Q}` 为角色视角映射，`S_r = {s | r∈Π(s)}`；
- `C_r ⊆ Q` 为角色能力域，`U = {u_r : Q → ℝ_{≥0}}` 为已标定不确定度；
- `q : R → ℕ` 为角色法定人数（quorum）。
角色 `r` 的 claim 记为 `ŷ_r = φ_r(o_{S_r})`，当 `S_r ≠ ∅` 时角色活跃。

**定义 122（角色一致性残差与证书 K_R）**
对角色 `r,r'` 及 `y ∈ C_r ∩ C_{r'}`，定义归一化残差
```
δ_{rr'}(y) = || ŷ_r - ŷ_{r'} ||_{Σ_{rr'}^{-1}}
δ_R = sup_{y ∈ ∩_{r∈R_*} C_r} max_{r<r'} δ_{rr'}(y)
```
其中 `Σ_{rr'}` 为两角色联合协方差，`R_*` 为当前活跃角色。角色一致性证书
`K_R = (cover_R, δ_R, τ_R, q, expiry)`，`cover_R = P_{y~D_Q}[ y∈∩_{r∈R_*}C_r ∧ quorate(R_*) ]`。若 `cover_R ≥ 1-α` 且 `δ_R ≤ θ_R`，称 `K_R` 在容差 `θ_R` 下 sound。

**定义 123（角色一致融合 RCF）**
给定 claims `{(ŷ_r,u_r)}_{r∈R_*}`，可行集
```
𝔽 = { x∈Q | ∀r,r': x∈C_r∩C_{r'} ⇒ δ_{rr'}(x) ≤ θ_R
            ∧ |{r : x∈C_r, |S_r|≥q(r)}| ≥ q_min }
```
若 `𝔽=∅`，融合返回 `⊥` 与**最小冲突角色集** `Cul`（不可静默平均）；否则
```
x* = argmin_{x∈𝔽} Σ_r w_r(x) u_r(x)^{-2} ||x-ŷ_r||^2
```
若存在角色无关锚点 `a`（锚定 `Q` 的原点/尺度），追加约束 `||x-ŷ_{r0}||_{Σ_a^{-1}} ≤ ε_a`。RCF 的输出是 `(x*, K_R)` 或 `(⊥, Cul)`，**不存在“低置信度但仍输出”的中间态**。

**定义 124（角色漂移、角色别名与挑战探针）**
在窗口 `[t,t+Δ]` 上定义角色漂移
```
D_role = d_Π(Π_t,Π_{t+Δ})
       + Σ_r [ d_C(C_r^t, C_r^{t+Δ}) + ||φ_r^t - φ_r^{t+Δ}||_{Lip} ]
       + |δ_R(t+Δ) - δ_R(t)|
```
**角色别名**：存在 `r'≠r` 使 `E_y[d(ŷ_r, φ_{r'}(y))] < E_y[d(ŷ_r, φ_r(y))]`，即传感器在“扮演”错误角色。**挑战探针** `p` 是只改变部分模态预期签名的微动作，其角色签名 `s_p(r)=∂φ_r/∂p`；选择 `p* = argmax_p det(I_role(p))`（角色可辨识 Fisher 信息），以最小扰动量换取最大别名可辨识度。

**定义 125（角色一致交接契约 RCH）**
云边角色交接 `H = (π_c, π_e, q, Δ_role, anchor_e, fallback)`。证书携带条件
```
carry(J_c, K_R, H) 合法 ⇔ D_role(π_c,π_e) ≤ Δ_role
                       ∧ δ_R^e ≤ θ_R
                       ∧ quorate(π_e, q)
                       ∧ A_core ∩ dom(γ_ce) ≠ ∅
                       ∧ anchor_e = true
```
任一条件失败则进入 `fallback`（安全冻结、重协商或降级为“仅观察”），绝不把云端角色分配下的证书直接贴到边端不同的角色分配上。

**定义 126（角色一致性联合证书与账本 JRC）**
角色联合证书 `J_R = (K_R, ρ_R, A_cert, π, D_role, L_R, anchor, expiry)`：
- `ρ_R = (ρ_r, K_role)` 为逐角色鲁棒性谱与跨角色耦合矩阵；
- `A_cert` 承接第 54 轮动作占用证书；
- `π` 为本次签发时的角色分配；
- `L_R` 为**角色账本**（append-only 哈希链：claim、裁决、探针、重标定事件）；
- `anchor` 标记是否存在角色无关锚点。
部署可判定条件：
```
dom(J_R)=in ∧ sound(K_R) ∧ D_role≤Δ_role ∧ quorate
             ∧ ρ_R≥ρ_min ∧ δ_a≤Θ_a ∧ anchor=true
```
若无 `anchor`，则 `J_R` 只能签发 **观察证书**（`dom=obs`），不得用于闭环动作部署。

### IP-121 RTS（Role-Typed Sensor Schema）

```python
def build_role_schema(sensors, task, alpha):
    R = task.roles
    Pi = {s: calibrate_roles(s, R) for s in sensors}
    Phi, C, U = {}, {}, {}
    for r in R:
        S_r = [s for s in sensors if r in Pi[s]]
        Phi[r] = fit_view(S_r, Q=task.quotient)
        C[r] = conformal_envelope(Phi[r], S_r, alpha)
        U[r] = calibrate_uncertainty(Phi[r], S_r)
    return RoleSchema(R, sensors, Pi, Phi, C, U, task.quotient, task.quorum)
```

### IP-122 RCF（Role-Consistent Fusion）

```python
def role_consistent_fuse(claims, schema, theta_R, q_min):
    active = {r for r, c in claims.items() if c.y in schema.C[r]}
    if not quorate(active, schema.q, q_min):
        return Bottom(reason='quorum', culprit=active)
    for r1, r2 in combinations(active, 2):
        if schema.disjoint(r1, r2):
            continue
        if maha(claims[r1], claims[r2]) > theta_R:
            return Bottom(reason='inconsistent',
                          culprit=role_explain(claims, schema))
    x = constrained_map(claims, active, schema)   # 加权最小二乘 + 可行域投影
    if schema.anchor and not anchor_ok(x, schema.anchor):
        return Bottom(reason='anchor_mismatch', culprit=schema.anchor_role)
    return Fused(x, K_R=make_role_cert(claims, schema, theta_R))
```

### IP-123 RCD（Role Consistency Drift Monitor）

```python
def detect_role_drift(ledger, window, probes, budget):
    D_pi = assignment_edit_distance(ledger.pi_t, ledger.pi_now)
    D_C = sum(wasserstein(ledger.C[r], ledger.phi_now.C[r]) for r in ledger.R)
    D_phi = sum(lip_norm(ledger.phi[r], ledger.phi_now[r]) for r in ledger.R)
    D_delta = abs(ledger.delta_R - current_delta_R(ledger))
    aliases = detect_aliases(ledger)                 # 跨角色响应签名错配
    if aliases and budget.probe_left > 0:
        p = choose_probe(aliases, ledger, maximize='role_fisher')
        aliases = disambiguate(p, aliases)
        D_pi += probe_cost(p)
    D_role = D_pi + D_C + D_phi + D_delta
    return ('drift', D_role, aliases) if D_role > budget.D_role else ('ok', D_role, [])
```

### IP-124 RCH（Role-Consistent Handover）

```python
def role_handover(pi_c, pi_e, J_c, Delta_role, theta_R, q, gamma_ce):
    K_e = evaluate_role_consistency(pi_e, J_c.claims)
    if not sound(K_e, theta_R):        return ('reject', 'role_inconsistent', K_e)
    if role_drift(pi_c, pi_e) > Delta_role:
        return ('reject', 'role_drift')
    if not quorate(pi_e, q):           return ('reject', 'quorum')
    if intersection(J_c.A_cert.core, domain(gamma_ce)) == empty:
        return ('reject', 'action_mismatch')
    if not anchor_ok_on_edge(pi_e):    return ('reject', 'anchor_missing')
    return ('ok', carry(J_c, K_e, pi_e))   # 账本追加交接事件
```

### IP-125 RCT（Role-Consistent Transfer Certificate）

```python
def role_transfer_certify(J_src, target, phi_map, budgets):
    delta_phi, delta_rho = {}, {}
    for r in J_src.R:
        r_t = phi_map.target_role(r)
        if r_t is None:
            return ('reject', 'missing_role', r)
        delta_phi[r] = role_view_drift(J_src.phi[r], target.phi[r_t])
        delta_rho[r] = max(0, J_src.rho[r] - target.rho_hat[r_t])
    delta_R = cross_role_residual_drift(J_src, phi_map)
    if (max(delta_phi.values()) > budgets.phi
            or sum(delta_rho.values()) > budgets.rho
            or delta_R > budgets.R):
        return ('reject', 'budget_exceeded', delta_phi, delta_rho, delta_R)
    if not target.anchor:
        return ('reject', 'anchor_missing')   # 一致但可能共同偏差
    return ('ok', RTC(J_src, target, delta_phi, delta_rho, delta_R,
                      ledger=J_src.L_R.append(phi_map)))
```

### IP-126 RCL（Role-Consistency Explain Loop / Ledger）

```python
def role_explain(claims, schema):
    base = consistency_energy(claims, schema)
    score = {}
    for r in claims:
        subset = {k: v for k, v in claims.items() if k != r}
        score[r] = base - consistency_energy(subset, schema)
    culprit = max(score, key=score.get)          # 最小冲突角色集的关键成员
    return Explanation(culprit, score,
                       remedy=recalibrate_or_reassign(culprit),
                       probe=suggest_probe(culprit))

def append_ledger(L_R, event):
    prev = L_R[-1].hash if L_R else GENESIS
    return L_R.append(Event(prev=prev, hash=H(prev, event), **event))
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| RTS | `O(|S|·|R|·|Q|)` | `O(|R|·|Q|)` | 能力域 conformal 覆盖、视角映射可校准 |
| RCF | `O(|R|²·|Q| + T_solve)` | `O(|R|·|Q|)` | 可行集非空、gate 不静默放行、锚点约束 |
| RCD | `O(|R|·|Q|·W)` | `O(|R|·W)` | 漂移单调、别名可被探针辨识 |
| RCH | `O(|S|·|R| + |A|)` | `O(|R|+|A|)` | 携带条件 sound、fallback 全覆盖 |
| RCT | `O(|R|·(|Q|+|𝔇_ρ|))` | `O(|R|·|𝔇_ρ|)` | 预算闭合、锚点随迁移保留 |
| RCL | `O(|R|²·|Q|)` | `O(|R|·|Q|)` | 冲突集最小性、账本不可篡改 |

**引理（锚点—一致性误差界）**
若锚点角色 `r0` 满足 `||ŷ_{r0}-x_true||_Q ≤ ε_a`，且对全部活跃角色 `δ_{r0 r}(x*) ≤ θ_R`，则
```
||x* - x_true||_Q ≤ ε_a + κ·θ_R,   κ = max_r σ_max(Σ_{r0 r}^{1/2})
```
即融合误差 = 锚点误差 + 一致性容差经协方差放大的项。

**正确性定理（Role-Consistent Certification Soundness）**
承接第 54 轮 (A26)–(A28)，新增：
- **(A29)** 每个角色的能力域 `C_r` 在源域上以 `1-α_r` 覆盖标定；
- **(A30)** 角色内 claim 已标定，且 quorum 假设下诚实角色占多数；
- **(A31)** 角色漂移有界 `D_role ≤ Δ_role`，迁移映射 `φ` 的 Lipschitz 常数有界；
- **(A32)** 至少存在一个角色无关物理锚点，用于锚定 `Q` 的原点与尺度。
则部署正确概率
```
P_correct ≥ 1 - α_anchor - Σ_r α_r - P(δ_R > θ_R)
              - P(D_role > Δ_role) - β_E
```
且**无静默不一致**：任何角色越出能力域或与 quorum 冲突的 claim，都会以概率 `≥ 1-β_E` 触发 `⊥` 与 `Cul`，而不会被平均进最终动作。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 任务商空间 `Q` 选错，导致一致性空洞或过严 | 高 | 由 `A_T` 反推 `Q`；对 `Q` 做敏感性与对抗证伪；保留多粒度 `Q` |
| “一致地错”（共同标定/同源仿真偏差） | 高 | 角色无关锚点 + 独立计量 + 定期物理挑战；无锚点只发观察证书 |
| 受约束融合频繁不可行，可用性坍塌 | 中高 | 角色冗余分级 + 软可行域 + 显式降级到安全模式，绝不静默平均 |
| 角色别名检测延迟大于交接窗口 | 高 | 主动探针前置 + 交接前强制 challenge；账本预检 |
| 能力域随分布漂移而过期 | 高 | 在线 conformal 更新 + 漂移触发重标定 + 账本过期机制 |
| 账本膨胀与隐私 | 低中 | 哈希链 + 分层摘要 + 只保留证据索引 |

## 6. 本轮最大风险

**一句话**：角色一致性把多传感器从证据堆叠升级为可裁决的角色契约，但其致命弱点是 **“一致 ≠ 正确”**——所有角色可能在同一错误商空间 `Q` 上彼此吻合（共同标定偏差、共同坐标系错位、同源仿真误差），此时 `δ_R` 极小、证书却系统性放行错误状态，因此必须保留至少一个**角色无关的物理锚点**并对 `Q` 本身做对抗性证伪，否则我们会把“共识错误”认证成“可信真值”。

# 第 55 轮产物 · 创新点清单 v32：GroundEdge-GenSim-RC（RTS×RCF×RCD×RCH×RCT×RCL）

> 承接第 54 轮产物 v31（GroundEdge-GenSim+++：ACS×SCOM×CEC×AEC×JTC）。本轮在“动作-鲁棒性双证书”之上，补齐其被长期忽略的**感知侧隐性前提**：证书是在某个角色分配 `π` 下签发的。新增 **角色化传感融合层** `𝕊`：
> - **RTS（Role-Typed Sensor Schema）**：把传感器建模为“角色 + 视角 + 能力域 + 不确定度”的契约；
> - **RCF（Role-Consistent Fusion）**：在角色能力域与一致性容差内做受约束融合，冲突时返回 `⊥` 而非静默平均；
> - **RCD（Role Consistency Drift Monitor）**：角色漂移与角色别名的在线监测 + 挑战探针消歧；
> - **RCH（Role-Consistent Handover）**：云边/传感器替换时的角色一致交接与证书携带；
> - **RCT（Role-Consistent Transfer Certificate）**：跨域迁移时逐角色与跨角色一致性的联合证书；
> - **RCL（Role-Consistency Explain Loop / Ledger）**：冲突角色定位、重标定/重分配与不可篡改角色账本。
>
> IP 编号：IP-121~IP-126（共 6 个新增），升级 IP-115/116/118/120 以显式纳入角色分配 `π` 与角色一致性证书 `K_R`。
> 版本命名：**v32 = GroundEdge-GenSim-RC**（Role-Consistent）。

## 1. 符号体系增量（新增定义 121–126）

| 符号 | 含义 |
|---|---|
| `ℛ=(R,S,Π,Φ,C,U,Q,q)` | 角色化传感模式：角色、传感器、分配、视角、能力域、不确定度、任务商空间、quorum |
| `Q` | 任务相关商空间（位姿/抓取点/接触力旋量/关节状态） |

| `K_R=(cover_R,δ_R,τ_R,q,expiry)` | 角色一致性证书 |

## 2. 关键算法 伪代码

### IP-121 RTS

```python
def build_role_schema(sensors, task, alpha):
    R = task.roles
    Pi = {s: calibrate_roles(s, R) for s in sensors}
    Phi, C, U = {}, {}, {}
    for r in R:
        S_r = [s for s in sensors if r in Pi[s]]
        Phi[r] = fit_view(S_r, Q=task.quotient)
        C[r] = conformal_envelope(Phi[r], S_r, alpha)
        U[r] = calibrate_uncertainty(Phi[r], S_r)
    return RoleSchema(R, sensors, Pi, Phi, C, U, task.quotient, task.quorum)

def quotient_from_actions(A_T, state):
    # Q 只保留动作会读取或改变的量，避免一致性空洞或过严
    touched = union(action.reads(s) | action.writes(s) for s in A_T)
    return project(state, touched)
```

### IP-122 RCF

```python
def role_consistent_fuse(claims, schema, theta_R, q_min):
    active = {r for r, c in claims.items() if c.y in schema.C[r]}
    if not quorate(active, schema.q, q_min):
        return Bottom(reason='quorum', culprit=active)
    for r1, r2 in combinations(active, 2):
        if schema.disjoint(r1, r2):
            continue
        if maha(claims[r1], claims[r2]) > theta_R:
            return Bottom(reason='inconsistent',
                          culprit=role_explain(claims, schema))
    x = constrained_map(claims, active, schema)    # 加权最小二乘 + 投影到可行域
    if schema.anchor and not anchor_ok(x, schema.anchor):
        return Bottom(reason='anchor_mismatch', culprit=schema.anchor_role)
    return Fused(x, K_R=make_role_cert(claims, schema, theta_R))

def constrained_map(claims, active, schema):
    x = weighted_lstsq([(claims[r].y, claims[r].u) for r in active])
    for _ in range(MAX_IT):
        violated = [(r1, r2) for r1, r2 in combinations(active, 2)
                    if not schema.disjoint(r1, r2)
                    and maha(claims[r1], claims[r2], x) > schema.theta_R]
        if not violated:
            return x
        x = project_onto_consistency(x, violated, schema)   # 不动点迭代
    raise Infeasible
```

### IP-123 RCD

```python
def detect_role_drift(ledger, window, probes, budget):
    D_pi = assignment_edit_distance(ledger.pi_t, ledger.pi_now)
    D_C = sum(wasserstein(ledger.C[r], ledger.phi_now.C[r]) for r in ledger.R)
    D_phi = sum(lip_norm(ledger.phi[r], ledger.phi_now[r]) for r in ledger.R)
    D_delta = abs(ledger.delta_R - current_delta_R(ledger))
    aliases = detect_aliases(ledger)          # 跨角色响应签名错配
    if aliases and budget.probe_left > 0:
        p = choose_probe(aliases, ledger, maximize='role_fisher')
        aliases = disambiguate(p, aliases)
        D_pi += probe_cost(p)
    D_role = D_pi + D_C + D_phi + D_delta
    if D_role > budget.D_role or aliases:
        return ('drift', D_role, aliases)
    return ('ok', D_role, [])

def choose_probe(aliases, ledger, maximize):
    # 只改变部分模态预期签名，最小扰动下最大化角色可辨识度
    return max(ledger.probe_pool,
               key=lambda p: role_fisher(p, aliases, ledger))
```

### IP-124 RCH

```python
def role_handover(pi_c, pi_e, J_c, Delta_role, theta_R, q, gamma_ce):
    K_e = evaluate_role_consistency(pi_e, J_c.claims)
    if not sound(K_e, theta_R):        return ('reject', 'role_inconsistent', K_e)
    if role_drift(pi_c, pi_e) > Delta_role:
        return ('reject', 'role_drift')
    if not quorate(pi_e, q):           return ('reject', 'quorum')
    if intersection(J_c.A_cert.core, domain(gamma_ce)) == empty:
        return ('reject', 'action_mismatch')
    if not anchor_ok_on_edge(pi_e):    return ('reject', 'anchor_missing')
    return ('ok', carry(J_c, K_e, pi_e))      # 账本追加交接事件
```

### IP-125 RCT

```python
def role_transfer_certify(J_src, target, phi_map, budgets):
    delta_phi, delta_rho = {}, {}
    for r in J_src.R:
        r_t = phi_map.target_role(r)
        if r_t is None:
            return ('reject', 'missing_role', r)
        delta_phi[r] = role_view_drift(J_src.phi[r], target.phi[r_t])
        delta_rho[r] = max(0, J_src.rho[r] - target.rho_hat[r_t])
    delta_R = cross_role_residual_drift(J_src, phi_map)
    if (max(delta_phi.values()) > budgets.phi
            or sum(delta_rho.values()) > budgets.rho
            or delta_R > budgets.R):
        return ('reject', 'budget_exceeded', delta_phi, delta_rho, delta_R)
    if not target.anchor:
        return ('reject', 'anchor_missing')   # 防止“一致地错”跨域传播
    return ('ok', RTC(J_src, target, delta_phi, delta_rho, delta_R,
                      ledger=J_src.L_R.append(phi_map)))
```

### IP-126 RCL

```python
def role_explain(claims, schema):
    base = consistency_energy(claims, schema)
    score = {}
    for r in claims:
        subset = {k: v for k, v in claims.items() if k != r}
        score[r] = base - consistency_energy(subset, schema)
    culprit = max(score, key=score.get)        # 最小冲突角色集的关键成员
    return Explanation(culprit, score,
                       remedy=recalibrate_or_reassign(culprit),
                       probe=suggest_probe(culprit))

def append_ledger(L_R, event):
    prev = L_R[-1].hash if L_R else GENESIS
    return L_R.append(Event(prev=prev, hash=H(prev, event), **event))
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| RTS | `O(|S|·|R|·|Q|)` | `O(|R|·|Q|)` | 能力域覆盖 `≥1-α`；`Q` 由 `A_T` 确定 |
| RCF | `O(|R|²·|Q| + T_solve)` | `O(|R|·|Q|)` | 可行域非空；冲突必返回 `⊥`；无静默平均 |
| RCD | `O(|R|·|Q|·W)` | `O(|R|·W)` | 漂移单调；别名在 Fisher 探针下可辨识 |
| RCH | `O(|S|·|R| + |A|)` | `O(|R|+|A|)` | 携带五条件 sound；fallback 全覆盖 |
| RCT | `O(|R|·(|Q|+|𝔇_ρ|))` | `O(|R|·|𝔇_ρ|)` | 预算闭合；锚点随迁移保留 |
| RCL | `O(|R|²·|Q|)` | `O(|R|·|Q|)` | 冲突集最小性；账本哈希链不可篡改 |

**引理（锚点—一致性误差界）**
若锚点角色 `r0` 满足 `||ŷ_{r0}-x_true||_Q ≤ ε_a`，且对全部活跃角色 `δ_{r0r}(x*) ≤ θ_R`，则
```
||x* - x_true||_Q ≤ ε_a + κ·θ_R,   κ = max_r σ_max(Σ_{r0r}^{1/2})
```

**正确性定理（Role-Consistent Certification Soundness）**
承接第 54 轮 (A26)–(A28)，新增：
- **(A29)** 每个角色能力域 `C_r` 在源域以 `1-α_r` 覆盖标定；
- **(A30)** 角色内 claim 已标定，quorum 假设下诚实角色占多数；
- **(A31)** 角色漂移有界 `D_role ≤ Δ_role`，迁移映射 `φ` 的 Lipschitz 常数有界；
- **(A32)** 至少存在一个角色无关物理锚点，锚定 `Q` 的原点与尺度。
则部署正确概率
```
P_correct ≥ 1 - α_anchor - Σ_r α_r - P(δ_R > θ_R)
              - P(D_role > Δ_role) - β_E
```
且**无静默不一致**：任何越出能力域或与 quorum 冲突的 claim，以概率 `≥1-β_E` 触发 `⊥` 与 `Cul`，不会被平均进最终动作。

**与第 54 轮证书的关系**
```
J_R = seal( J_54 = (ρ, A_cert, γ_ce, δ_a),
            π, K_R, D_role, L_R, anchor )
```
即第 54 轮联合证书 `J` 是本轮 `J_R` 在“角色分配固定且已锚定”时的特例。签发 `J_54` 前必须先通过 RCF 的角色一致 gate；`J_54` 失效的一个此前未被建模的原因，就是 `π` 漂移而 `J_54` 本身字段未变。

## 5. 实验设计 E162–E167

| 实验 | 指标 | 目标 |
|---|---|---|
| E162 角色能力域标定 | 逐角色 conformal 覆盖率 vs 名义 `1-α` | 偏差 ≤ 2% |
| E163 角色一致性与任务误差 | `δ_R` vs 端到端位姿/抓取误差 | 相关 ≥ 0.7；虚假一致率 ≤ 3% |
| E164 角色漂移/别名检测 | 传感器对调、延迟反转、坐标系蠕变 | P95 延迟 ≤ 2 个控制周期；误报 ≤ 5% |
| E165 云边角色交接 | 交接后成功率 vs 直接贴证书 | 提升 ≥ 15%；不安全交接 ≤ 1% |
| E166 sim-to-real 角色迁移 | 逐角色标定漂移 + 跨角色残差漂移 | 成功率下降 ≤ 8%；锚点保留率 100% |
| E167 角色 Explain 与恢复 | 冲突角色定位准确率、恢复时间、成功率增益 | 定位 ≥ 90%；恢复 ≤ 3 s；增益 ≥ 12% |

**消融设计**
1. `−anchor`：去掉角色无关锚点，预期出现“一致但错”的系统性失败（验证灵感 3）；
2. `−quorum`：去掉角色法定人数，预期角色别名导致静默错误（验证灵感 4）；
3. `−ledger`：去掉角色账本，预期云边交接与跨域迁移证书失效（验证灵感 5）；
4. `Q-full` vs `Q-task`：用全部状态维度作商空间，预期一致性过严、可用性坍塌。

**与既有实验的衔接**
- E160 的“联合证书有效性”应在 E162–E163 通过后才统计，否则会把感知层的共同偏差误记为动作层收益；
- E161 的“反向解释驱动重剖分”与 E167 的“角色 Explain”共享解释信道，需区分“动作根因”与“角色根因”。

## 6. 本轮最大风险

**一句话**：角色一致性把多传感器从证据堆叠升级为可裁决的角色契约，但其致命弱点是 **“一致 ≠ 正确”**——所有角色可能在同一错误商空间 `Q` 上彼此吻合（共同标定偏差、共同坐标系错位、同源仿真误差），此时 `δ_R` 极小、证书却系统性放行错误状态，因此必须保留至少一个**角色无关的物理锚点**并对 `Q` 本身做对抗性证伪，否则我们会把“共识错误”认证成“可信真值”。
