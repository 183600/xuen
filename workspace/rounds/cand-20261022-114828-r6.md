# 想法区 · 第 6 轮：从 X-DUB/PC 到 X-DUB/OL

**灵感词**：reinforcement learning / average-case analysis / online algorithm  
**起点**：v0.3「X-DUB/PC」。它已经有一套很强的证书架构：时间价格对偶、聚合 ER/DFF、打包核、指数 B&B、MCTS 上界和证明树。本轮不推翻它，只修两个具体缺口：**内部状态里的箱子不是满窗口的**，以及**证书控制器不知道核什么时候值得找**。

## 一句话直觉：先让箱子知道机器什么时候空，再让控制器知道核什么时候值得找

v0.3 的 `L_PC` 对窗口 `[a,b)` 给每台机器同样的容量 `b-a`。这在根节点成立，因为所有机器从 0 开始可用；但在 B&B 内部状态，机器 `k` 可能要到 `A_k` 才空。此时窗口内真正可用的容量是 `max(0, b - max(a, A_k))`，不是 `b-a`。把容量改成这个异构向量，就得到本轮的新下界 **AVAIL-CORE**。它严格强于 v0.3 的打包核；根节点两者相等，内部状态可以强很多。

第二个缺口更隐蔽：v0.3 的核搜索是启发式的，`k_core`、窗口预算、UCB 加倍都没有解释“为什么这个核应该存在”。我从子集和的局部极限定理看到一个**平均情况相变**：对 m=2，强制集 `X` 的 2-bin 可装性由“落在 `[P(X)-C,C]` 的子集和个数”控制，其期望约为

```text
E[N] ≈ 2^{|X|} · (s+1) / (σ_X · sqrt(2π)),
s = 2C - P(X),   σ_X² = Σ_{i∈X} p_i² / 4.
```

`E[N] << 1` 时核很可能不可行（值得找）；`E[N] >> 1` 时核很可能可行（应该跳过，换对偶/DFF/AVAIL）。这张相变图解释了 v0.3 的一个实验结果：无依赖家族 30/30 精确闭合，而随机 DAG 只有 28/30 精确、3/30 有改进——不是核搜索不够努力，而是稠密 DAG 的强制集往往太大、太松，打包核在平均情况下就不可行性不足。

> 我还检查过“从全强制集里随机抽子核”这个想法。它不成立：装箱不可行性对子集是单调的——若 `BP(X)` 可行，则任意 `X'⊆X` 都可行。所以全强制集已经是同一窗口下最强的核，抽子核只能让证书变小，不能制造新的不可行性。这个负结果把本轮引向“换容量”和“换证书族”，而不是“更聪明地抽子集”。

## 三个灵感词分别补什么

- **average-case analysis**：给出 2-bin 打包核的相变公式，并用它给窗口排序。预测分数只用于“先试哪个窗口/是否值得跑精确子集和”，最终仍由 checker 验证；预测错了只损失时间，不损失正确性。
- **online algorithm**：把“窗口搜索 + 证书族选择”看成一个在线决策序列。窗口按预测分数排序后逐个测试，成功即停；证书族由 bandit 在线选择。没有一个决策需要知道未来的节点或未来的失败。
- **reinforcement learning**：用代价敏感的 contextual LinUCB 学习“在什么状态下先跑哪个证书/搜索动作”。奖励是**已验证的间隙下降 / 成本**；bandit 只排序，不剪枝。证书检查器是可信基，bandit 是可信基之外的可替换策略。

## 核心方案：X-DUB/OL

在 v0.3 上做四处增量：

1. **AVAIL-CORE**：新下界 `L_AV(σ)`。对窗口 `W=[a,b)`，机器 `k` 的容量改为
   ```text
   cap_k(W,σ) = max(0, b - max(a, A_k)).
   ```
   强制集 `X_W` 不变；若异构装箱 `BP(X_W, caps)` 不可行，则 `H` 不可行。`L_AV ≥ L_PC`，根节点相等，内部状态严格更强。m=2 用精确子集和区间判据；m>2 用聚合/最小容量 DFF/小核 PACK-BB。

2. **PHASE-RANK**：平均情况相变预测器。对每个候选窗口计算 `E_phase(W)`，按从小到大排序；聚合不可行的窗口排最前，`W(X)≤C` 的平凡可行窗口排最后。精确测试按这个顺序进行，成功即停。它把 v0.3 的“启发式窗口分数”换成一个有概率解释的排序。

3. **CERT-BANDIT**：安全护盾下的在线学习控制器。动作集是 `{ER, DFF, PC, AV, DUAL, BBF, MCTS}`；上下文是优先级密度、能量松弛、`p_max/H`、机器不平衡度、强制集比例、相变分数；奖励是 `(ΔL+ΔU)/cost`。用 LinUCB 选择动作；每 `K_fair` 步强制一次 BBF、一次 MCTS，保证 B&B 前沿不会饿死。失败/拒绝的证书不改变 `L`，因此控制器无法破坏正确性。

4. **PROOF 扩展**：证明树新增 `PACK-CORE-AVAIL` 节点。checker 独立重算 `lo_i,q_i,A_k`，验证 `X_W` 的强制性、异构容量、以及装箱不可行证据（AGG/DFF/SUBSET/PACK-BB）。bandit 和相变预测器不在证明树里。

组合下界：

```text
L_X4(σ) = max( L_D(σ), L_AV(σ) )
```

因为 `L_AV ≥ L_PC`，所以 `L_X4` 支配 v0.3 的 `L_X3 = max(L_D, L_PC)`。关闭 AVAIL 并把所有 `cap_k` 强制为 `b-a`，就退回 v0.3；关闭 bandit 得到固定证书阶梯；全部打开是完整算法。

## 本轮要验证的命题

1. **AVAIL 可采纳**：若 `BP(X_W, caps(W))` 不可行，则从 `σ` 出发不存在 makespan ≤H 的调度；因此 `L_AV ≤ OPT`。
2. **AVAIL 支配 PC**：`cap_k(W) ≤ b-a`，所以同一窗口的 PC 不可行性蕴含 AVAIL 不可行性；`L_AV ≥ L_PC`，根节点相等。
3. **相变命题**：在局部极限定理适用的随机子集模型下，2-bin 可装概率随 `E[N]` 单调上升，转变点约在 `E[N]≈1`；实验上 k=5..12 的可装率从 8.7% 升到 99.4%。
4. **PHASE-RANK 降低精确测试次数**：在随机 DAG 的窗口选择实验里，它找到核的成功率与 v0.3 启发式相同，但平均精确测试次数约减半（17.7→7.7、33.8→17.1、36.4→18.4）。
5. **端到端节点数下降**：在 n=7, m=2 的 12 个随机 DAG 上，同一 B&B/同一 greedy 上界，`L0+AVAIL` 的总扩展节点数为 200，`L0+PC` 为 26,470；两版返回相同 OPT。
6. **bandit 安全**：任何策略选择都不会破坏 `L≤OPT≤U` 或证明树；失败只影响 anytime 质量。
7. **bandit 有在线保证**：在标准 LinUCB 假设下，累积 regret 为 `O(d√(T log T))`；平均奖励以 `O(d√(log T/T))` 收敛到最佳线性策略。
8. **v0.3 可恢复**：固定 bandit 为 v0.3 的顺序、关闭 AVAIL，就得到 v0.3 的行为（除实现细节外）。

## 初步结果与边界

- **AVAIL 状态实验**：1772 个随机可达状态（n=9, m=2, P=10, 边概率 0.35，随机前缀调度，H=C(σ)+0..10）。PC 在 1397 个状态上找到不可行窗口，AVAIL 在 1457 个状态上找到；**1270 个状态存在 AVAIL-only 不可行窗口，0 个状态存在 PC-only 不可行窗口**（支配关系成立）。
- **相变标定**：固定 P=100、slack s=0，k=5..12 的 2-bin 可装率分别为 8.7%、15.5%、26.9%、45.3%、70.1%、92.5%、97.4%、99.4%；平均预测 `E[N]` 从 0.21 升到 16.81。固定 k=8、s=0..20，可装率从 40.7% 升到 99.5%。这是纯 Python 的子集和实验，不是完整实例。
- **PHASE-RANK 窗口实验**：n=10/12 的随机 DAG，每个设置 300 个实例；在存在核的实例上，v0.3 启发式与 PHASE-RANK 都能找到核，但后者平均精确测试次数约为前者的一半（见产物区表）。
- **端到端 B&B 实验**：12 个 n=7、m=2、P=10、边概率 0.3 的随机 DAG；PC 版总节点 26,470，AVAIL 版 200；两版 OPT 完全一致。样本很小，但这是“状态层下界 → 搜索树”的第一条端到端证据。
- **bandit 实验**：600 个混合家族状态（随机 DAG/两层 DAG/无依赖）。LinUCB 的成功率与最佳固定顺序相同（0.545），但平均成本略高（20.9 vs 19.9）；表格 UCB 的平均成本为 19.6，仅略低于最佳固定顺序；oracle 成本是 3.36。**我没有观察到 bandit 显著超过最佳固定顺序**——廉价特征不足以预测哪个 arm 会成功。这个负结果很重要：本轮的主要增益来自 AVAIL 和 PHASE-RANK，RL 层是安全、可移植的控制层，不是性能魔法。
- **尚未做**：m>2 的精确异构装箱、PSPLIB/fork-join 规模实验、独立 checker 对拍、完整 B&B 在 n≥20 的 anytime 曲线、非平稳 bandit 的 regret 保证。

## 本轮的一句话最大风险

**当前方案最大的风险是：AVAIL 只在内部状态严格强于 PC，而 bandit 的离线/在线增益在廉价特征下可能很有限；在大型 precedence-heavy 实例上，新增的异构装箱与控制器开销可能抵消节点数下降。**

   它严格支配 `L_PC`，根节点相等，内部状态可以严格更强。

3. **CERT-BANDIT**：带安全护盾的 contextual LinUCB，在
   `{ER,DFF,PC,AV,DUAL,BBF,MCTS}` 中选择动作；奖励是已验证的间隙下降/成本。
   每 `K_fair` 步强制一次 BBF、一次 MCTS，保证搜索公平性。
4. **PROOF 扩展**：新增 `PACK-CORE-AVAIL` 节点；checker 独立重算

```text
关闭 AVAIL（所有 cap_k 强制为 b-a） + 关闭 bandit（固定 v0.3 顺序） → v0.3
```

## 1. 问题、符号与复用的旧结论

### 1.1 形式化问题

```text
P | prec | Cmax
```

给定任务集 `V={1,...,n}`、工时 `p_i∈Z_{≥1}`、优先约束 `E⊆V×V`（DAG）、同构机器数 `m`。调度由开始时间 `s_i` 与机器 `μ_i` 组成，满足：

```text
(i,j) ∈ E  ⇒  s_j ≥ s_i + p_i
μ_i = μ_j  ⇒  [s_i, s_i+p_i) 与 [s_j, s_j+p_j) 不重叠
```

目标 `Cmax = max_i(s_i+p_i)` 最小；最优值记 `OPT`。

### 1.2 符号表（v0.4 新增/重定义）

| 符号 | 含义 |
|---|---|
| `σ=(S,A,c)` | 状态：已调度集、机器可用时间、完成时间 |
| `R=V\S` | 未调度集 |
| `C(σ)=max_k A_k` | 状态已完成时间 |
| `lo_i(σ)` | 动态 head：`i` 的最早可能开始，含已调度前驱 |
| `q_i(σ)` | 动态 tail：`i` 之后（不含 `p_i`）的残余最长路径 |
| `W=[a,b)` | 时间窗口，`C=b-a` |
| `P(X)` | `Σ_{i∈X} p_i`（避免与窗口 `W` 混淆） |
| `X_W(σ,H)` | 强制集 `{i∈R: lo_i≥a, H-q_i≤b}` |
| `cap_k(W,σ)` | `max(0, b-max(a,A_k))`，机器 `k` 在 `W` 内的可用容量 |
| `caps(W,σ)` | 向量 `(cap_1,...,cap_m)` |
| `BP(X,caps)` | 异构装箱：把 `X` 分到容量 `caps_k` 的箱子，每箱负载 ≤容量 |
| `L_AV(σ)` | 可用时间感知的打包核下界 |
| `L_X4(σ)` | `max(L_D(σ), L_AV(σ))` |
| `E_phase(W)` | 2-bin 子集和相变预测值 |
| `φ(σ,H)` | bandit 上下文特征向量 |
| `A_arms` | 证书/搜索动作集合 |
| `K_fair` | 公平护盾周期 |
| `α,λ` | LinUCB 探索系数与岭参数 |

### 1.3 复用的 v0.3 结论

以下结论直接继承，不再证明：

- **动作覆盖性**：动作 `(i,k)`（`i∈Ready(σ)`，`k∈{1,...,m}`）在
  `t=max(A_k, max_{j∈pred(i)} c_j)` 开始；从根出发的某条动作序列可达到一个最优调度。
- **CP 初始上界**：按 `q_i` 降序的 CP 表调度得到可行 `U_0`，且
  `U_0≤(2-1/m)OPT`（Graham）。
- **前沿下界**：若 `F` 是覆盖所有“可能优于 `U`”的剩余调度的切口，则
  `min_{v∈F} LB(v)≤OPT`。
- **对偶证书**：`g_H(σ,λ)>0 ⇒ H<OPT(σ)`；`L_D` 可采纳。
- **指数 B&B**：`X-EXACT` 在动作树上做 best-first；若因 `F=∅` 或 `L≥U` 终止，则 `U=OPT`。
- **证明树**：`TERMINAL/PRUNED/EXACT/EXHAUSTED` 的局部检查规则可靠。

v0.4 只替换/扩展 `LB`、`CERTIFY` 和控制器，并给证明树加一种叶子证书。

## 2. 动机：两个具体缺口

### 2.1 缺口一：状态里的箱子不是满窗口的

v0.3 对窗口 `W=[a,b)` 使用统一容量 `C=b-a`。这只在 `A_k≤a`（机器在整个窗口都可用）时成立。内部状态里，机器 `k` 可能要到 `A_k>a` 才空；窗口内真正可用的容量是

```text
cap_k(W,σ) = max(0, b - max(a, A_k)).
```

**例 A**：

```text
m=2
状态 σ：M0 在 0 时刻空，M1 要到 8 时刻才空，即 A=(0,8)
剩余任务：三个 p=3 的任务，无优先约束
H=8
```

- v0.3：窗口 `[0,8)`，`C=8`，`X={三个任务}`，总工时 9。两个容量 8 的箱子装得下 9，所以 `L_PC=8`。
- 实际：M1 在 `[0,8)` 内贡献 0；窗口内总容量是 `8+0=8<9`，所以 `H=8` 不可行。
- AVAIL：`caps=(8,0)`，`BP(X,caps)` 不可行，直接认证 `H=8`。

这个例子说明：v0.3 的 `L0=max(8,ceil(9/2)=5)=8` 和 `L_PC=8` 都停在 8，而 AVAIL 把它推到 9。

### 2.2 缺口二：核的成败有平均情况相变

v0.3 的核搜索假设“更努力地找，就可能找到更强的核”。但装箱不可行性对子集是单调的：

> 若 `X'⊆X` 且 `BP(X')` 不可行，则 `BP(X)` 也不可行。  
> 逆否：若 `BP(X)` 可行，则任意 `X'⊆X` 都可行。

因此，**全强制集已经是同一窗口下最强的核**；抽子核只能让证书变小，不能制造新的不可行性。v0.3 在随机 DAG 上只有 3/30 改进，不是搜索不够努力，而是全强制集在平均情况下往往可装箱。

对 m=2，`BP(X,2,C)` 的可装性等价于“存在子集和落在 `[P(X)-C, C]`”。把 `X` 的每个任务以 1/2 概率放入随机子集 `Y`，令 `S=P(Y)`。在局部极限定理适用的随机模型下，

```text
Pr[S=t] ≈ (1/(σ_X√(2π))) exp(-(t-P(X)/2)²/(2σ_X²)),
σ_X² = Σ_{i∈X} p_i² / 4.
```

区间 `[P(X)-C, C]` 的中心是 `P(X)/2`，长度为 `s+1`，其中 `s=2C-P(X)`。于是落在区间内的子集个数期望为

```text
E[N] ≈ 2^{|X|} · (s+1) / (σ_X · sqrt(2π)).
```

- `E[N] << 1`：区间内几乎没有子集和，核很可能不可行，值得跑精确子集和；
- `E[N] >> 1`：区间内有很多子集和，核很可能可行，应该跳过，换 DFF/对偶/AVAIL。

第 4 节给出形式和实验。这个相变是 PHASE-RANK 的依据。

### 2.3 缺口三：控制器没有“为什么现在跑这个证书”的解释

v0.3 的 `ADAPT-CERT` 用 UCB、特征路由、失败加倍，但没有把“证书选择”形式化为一个在线决策问题。v0.4 把它写成一个代价敏感的 contextual bandit：

- 状态：当前 B&B 前沿、间隙、节点特征；
- 动作：`ER/DFF/PC/AV/DUAL/BBF/MCTS`；
- 奖励：已验证的间隙下降 / 成本；
- 安全护盾：证书必须通过 checker；BBF/MCTS 按固定周期强制，防止饿死。

bandit 只决定“先试哪个”，不决定“是否可信”。这是本轮把 RL 放进可信系统的方式。

## 3. AVAIL-CORE

### 3.1 定义

固定状态 `σ=(S,A,c)` 和候选截止期 `H≥C(σ)`。对窗口 `W=[a,b)`：

```text
C = b-a
X_W = { i∈R : lo_i ≥ a,  H - q_i ≤ b }
cap_k(W,σ) = max(0, b - max(a, A_k)),   k=1,...,m
caps(W,σ) = (cap_1,...,cap_m)
```

**定义 1（AVAIL 核）**：`BP(X_W, caps(W,σ))` 问是否存在划分
`X_W = X_1 ∪ ... ∪ X_m`，使得每个 `k` 都有 `P(X_k) ≤ cap_k`。

**定义 2（AVAIL 下界）**：

```text
L_AV(σ) = max( L0(σ),
               1 + max { H∈Z : 存在窗口 W 使 BP(X_W, caps(W,σ)) 不可行 } )
```

其中 `L0(σ)=max(C(σ), max_{i∈R}(lo_i+p_i+q_i), ceil(P(R)/m))`。空集 max 约定为 `-∞`。

### 3.2 可采纳性

**引理 1（强制在窗口内）**：若从 `σ` 出发存在 makespan ≤H 的调度，则对任意窗口 `W=[a,b)` 和任意 `i∈X_W`，`i` 的执行区间完全落在 `[a,b)` 内。

**证明**：由 `lo_i` 的定义，`s_i≥lo_i`；由 `q_i` 的定义，`s_i+p_i≤H-q_i`。若 `i∈X_W`，则 `lo_i≥a` 且 `H-q_i≤b`，所以 `a≤s_i<s_i+p_i≤b`。证毕。

**引理 2（机器容量）**：在上述调度中，若 `X_W` 中分到机器 `k` 的任务集为 `Y_k`，则
`P(Y_k) ≤ cap_k(W,σ)`。

**证明**：机器 `k` 在 `A_k` 之前不可用；这些任务都在 `W` 内执行且互不重叠，所以它们的总执行时间不超过区间 `[max(a,A_k), b)` 的长度，即 `b-max(a,A_k)`；若该长度为负，则没有任务能在 `W` 内执行，容量为 0。证毕。

**定理 1（AVAIL 可采纳）**：若 `BP(X_W,caps(W,σ))` 不可行，则从 `σ` 出发不存在 makespan ≤H 的调度。

**证明**：反设存在这样的调度。由引理 1，`X_W` 中每个任务都在 `W` 内执行。按调度使用的机器把 `X_W` 分成 `Y_1,...,Y_m`。由引理 2，`P(Y_k)≤cap_k`。这是一个 `BP(X_W,caps)` 的可行装箱，矛盾。证毕。

**推论 1**：`L_AV(σ) ≤ OPT(σ)`。

**证明**：若认证集合为空，`L_AV=L0≤OPT`。否则对任意被认证的 `H`，定理 1 给出 `H<OPT(σ)`；由于 `H` 整数，`H≤OPT(σ)-1`。取最大再 +1，仍不超过 `OPT(σ)`；与 `L0` 取 max 也不超过。证毕。

### 3.3 支配 v0.3 的打包核

**定理 2（AVAIL 支配 PC）**：对任意 `σ,W`，`cap_k(W,σ) ≤ b-a = C`。因此
`BP(X_W,[C,...,C])` 不可行 ⇒ `BP(X_W,caps(W,σ))` 不可行。于是
`L_AV(σ) ≥ L_PC(σ)`。

**证明**：`max(a,A_k) ≥ a`，所以 `b-max(a,A_k) ≤ b-a`；若 `max(a,A_k)>b`，容量为 0，更小。容量变小只会让装箱更难，所以 PC 的不可行性保持。证毕。

**根节点相等**：在根节点 `A_k=0`，且窗口端点 `a≥0`，所以 `max(a,A_k)=a`，`cap_k=b-a=C`。因此 `L_AV(root)=L_PC(root)`。**AVAIL 的收益全部来自内部状态**，这是本轮必须诚实说明的边界。

### 3.4 精确的 m=2 判据

**引理 3（两箱异构判据）**：设 `caps=(c_0,c_1)`，`P=P(X)`。`BP(X,caps)` 可行当且仅当存在子集 `Y⊆X` 使得

```text
P(Y) ≤ c_0   且   P - P(Y) ≤ c_1,
```

等价地，

```text
P(Y) ∈ [ max(0, P-c_1), min(c_0, P) ].
```

**证明**：若存在划分 `(Y,X\Y)`，两箱负载分别为 `P(Y)` 与 `P-P(Y)`，条件直接成立。反之，若 `Y` 的和落在区间内，则 `Y` 装进箱 0、`X\Y` 装进箱 1，给出可行划分。证毕。

实现：用 bitset 计算 `X` 的所有可达子集和（截断到 `max(c_0,c_1)`）；若区间与可达集合不相交，则不可行。若 `P>c_0+c_1`，聚合不可行；若 `P≤max(c_0,c_1)`，平凡可行（全放较大的箱子）。

### 3.5 m>2 的证据

m>2 的精确异构装箱是 NP-hard。v0.4 只用三种可检查证据：

- `AGG`：`P(X) > Σ_k cap_k`；
- `DFF(k)`：用 `C_min = min_k cap_k`，若 `Σ_{i∈X} u_k(p_i;C_min) > m`，则不可行（每台机器的容量都不超过 `C_min`，所以这是保守但有效的判据）；其中 `u_k(p;C)=ceil(p/C)` 若 `C>0`，否则 `∞`；
- `PACK-BB`：仅当 `|X|≤k_core` 时运行异构装箱 B&B（工件降序、相同剩余容量的箱子去重），输出一棵可递归检查的搜索树。预算耗尽返回 `UNKNOWN`，退回 DFF/对偶。

本轮实验只做 m=2 的精确判据；m>2 的 `PACK-BB` 检查器和规模实验留到下一轮。

### 3.6 与 v0.3 的关系

```text
L_AV ≥ L_PC（所有状态）
L_AV = L_PC（根节点）
```

因此 v0.4 的 `L_X4=max(L_D,L_AV)` 支配 v0.3 的 `L_X3=max(L_D,L_PC)`。但这是一个**状态层**的改进：它不会改变根节点的界，只在 B&B 展开后发挥作用。端到端收益取决于树中有多少内部状态需要 `A_k` 信息；第 11 节的 n=7 实验给出了第一份证据。

## 4. 平均情况分析：2-bin 打包核的相变

### 4.1 随机子集模型

固定强制集 `X`，`|X|=k`，`P=P(X)`，容量 `C`，`s=2C-P≥0`。令 `Y` 为 `X` 的均匀随机子集（每个任务以 1/2 概率入选），`S=P(Y)`。`BP(X,2,C)` 可行当且仅当存在 `Y` 使 `P-C≤S≤C`，即 `S∈[P-C,C]`。

### 4.2 局部极限定理

**命题 1（平均情况相变，局部 CLT 形式）**：假设 `p_i` 的分布非周期、方差有界、不过度集中。则对中心区域的 `t`，

```text
Pr[S=t] = (1/(σ_X√(2π))) exp(-(t-P/2)²/(2σ_X²)) + o(1/σ_X),
σ_X² = Σ_{i∈X} p_i² / 4.
```

因此

```text
E[# {Y : S∈[P-C,C]}]
  = 2^k · Pr[S∈[P-C,C]]
  ≈ 2^k · (s+1) / (σ_X√(2π)).
```

区间 `[P-C,C]` 的中心是 `P/2`，长度是 `s+1`，所以指数因子在中心处为 1。

**解释**：

- 若 `E[N]≪1`，区间内几乎没有子集和，`BP` 很可能不可行；
- 若 `E[N]≫1`，区间内有很多子集和，`BP` 很可能可行；
- 转变点大约在 `E[N]≈1`。

**边界**：这是渐近命题；对小 `|X|`（例如 `k≤4`），局部 CLT 可能明显偏离，公式可能把可行集预测成不可行。因此算法只把它当作**排序分数**，并在 `|X|` 很小时直接跑精确子集和。预测错误不影响正确性。

### 4.3 标定实验

**设置**：纯 Python；`P=100`；每个 `k` 生成 400 组随机工时，保留总工时偶数的组；`C=P(X)/2`（即 `s=0`）；用 bitset 精确判断 2-bin 可行性。表中 `pred` 是组内平均 `E[N]`，`feas` 是经验可装率。

| 7 | 201 | 0.70 | 0.269 |

### 4.4 对 v0.3 实验的解释

v0.3 的 90 个小实例中，无依赖家族 CORE 精确 30/30，而随机 DAG 只有 28/30、改进 3/30。相变给出一个解释：

- 无依赖实例的强制集通常就是“所有剩余任务”，且 `H` 接近 `P/m`，slack 小，`E[N]` 小，核容易不可行；
- 随机 DAG 的强制集受 `lo/q` 限制，往往更小、更松，`E[N]` 大，核容易可行；真正的冲突是顺序/空闲，而不是整数装箱。

因此，**在稠密 DAG 上继续加深核搜索是低收益的**；更好的策略是路由到对偶/DFF，或者用 AVAIL 看见机器可用时间。这正是 CERT-BANDIT 的动机。

## 5. PHASE-RANK：在线窗口搜索

### 5.1 分数

对固定 `σ,H` 和候选窗口 `W=[a,b)`，令 `X=X_W`，`C=b-a`，`P=P(X)`，`s=2C-P`。

```text
score(W) =
  -∞,                  P > 2C          # 聚合不可行，最优先
  +∞,                  P ≤ C           # 平凡可行，最后
  E_phase(W),          否则             # 2-bin 相变预测
```

其中

```text
E_phase(W) = 2^{|X|} · (s+1) / (σ_X√(2π)),
σ_X² = Σ_{i∈X} p_i² / 4.
```

对 AVAIL，精确测试使用真实的 `caps(W,σ)`；分数仍用统一 `C` 作为窗口尺度的近似。原因是相变公式是为同构 2-bin 推导的；AVAIL 的异构容量只会让装箱更难，所以“同构预测可行”的窗口在 AVAIL 下仍可能不可行，排序不会因此变坏到不可用。更好的做法是用 `C_eff=min_k cap_k` 或 `C_eff=(Σ caps)/m` 重新计算分数；本轮实验用统一 `C`，把 `C_eff` 留作消融。

### 5.2 算法

```text
函数 PHASE-RANK(σ, H, candidates, arm)
────────────────────────────────────────────────
1  scored ← ∅
2  for W in candidates:
3      X ← FORCED(W); C ← b-a; P ← Σ_{i∈X} p_i
4      if P > 2C:      score ← -∞
5      elif P ≤ C:     score ← +∞
6      else:           score ← E_phase(W)
7      scored ← scored ∪ {(score, W)}
8  sort scored by score ascending
9  for (score, W) in scored:
10     if score = +∞ and |scored| > B_cheap: break
11     verdict, π ← EXACT-ARM(arm, σ, H, W)
12     if verdict = INFEASIBLE:
13         return PACK-CORE-AVAIL(H, W, X_W, π)
14 return FAIL
```

`EXACT-ARM` 根据 `arm` 选择 ER/DFF/PC/AVAIL 的精确测试；`candidates` 是事件窗口集合：

```text
E(σ,H) = {0,H} ∪ {lo_i : i∈R} ∪ {H-q_i : i∈R}
```

小 `n` 时枚举全部 `O(n²)` 窗口；大 `n` 时用种子 + 束搜索，种子包括全窗口、每个任务的紧窗口、对偶价格高峰、当前 incumbent 关键路径。搜索不完整只影响下界强度，不影响正确性。

### 5.3 在线/平均情况解释

在相变模型下，`score` 越小，`BP` 可装概率越低。若真实不可行窗口在分数序中的排名为 `r`，PHASE-RANK 在 `r` 次精确测试内找到它。v0.3 的启发式分数也把“违反/接近违反”排在前面，但没有概率解释；两者在实验中都能找到核，差别在测试次数。

这不是一个 worst-case 竞争比：若所有不可行窗口的分数都很大，PHASE-RANK 可能先测试很多可行窗口。它的保证是**平均情况**的：在相变模型下，分数与可装概率单调相关，所以期望排名接近最优。我们把它称为 `average-case competitive`，而不是 worst-case competitive。

### 5.4 窗口选择实验

**设置**：随机 DAG，`m=2`；`H=L0+U{0,1,2,3}`；枚举全部事件窗口；用 m=2 精确子集和判断每个窗口是否不可行；比较

- **v0.3 heuristic**：按 v0.3 的分数
  `max(0,P-2C)+max(0,DFF-2)+1/(1+max(0,2C-P))+|X|/n` 降序测试；
- **PHASE-RANK**：按 `E_phase` 升序测试；
- **oracle**：是否存在任一不可行窗口。

两者都测试到成功或耗尽；表中“平均测试”是到第一次成功的精确测试次数。

| `n` | 边概率 | `P` | 有核实例 | v0.3 成功/平均测试 | PHASE 成功/平均测试 |
|---:|---:|---:|---:|---:|---:|
| 10 | 0.2 | 10 | 6/300 | 6/6, 17.7 | 6/6, 7.7 |
| 10 | 0.4 | 10 | 35/300 | 35/35, 33.8 | 35/35, 17.1 |
| 12 | 0.3 | 20 | 51/300 | 51/51, 36.4 | 51/51, 18.4 |

**解读**：

- 在“有核”的实例上，两者都能找到核（因为最终会测试所有窗口）；差别是测试次数。
- PHASE-RANK 平均少测约一半，说明相变分数确实把更可能不可行的窗口排到了前面。
- 这个实验只测 m=2 的 PC/AVAIL 窗口，不包含对偶/DFF；它验证的是“排序”，不是“完整证书组合”。

## 6. CERT-BANDIT：带安全护盾的在线学习

### 6.1 形式化

在每个决策时刻 `t`，算法观察到上下文 `φ_t∈R^d`，选择一个动作
`a_t∈A_arms`，支付成本 `c_t`，然后观察到奖励 `r_t∈[0,1]`。动作集合：

```text
A_arms = {ER, DFF, PC, AV, DUAL, BBF, MCTS}
```

- `ER/DFF/PC/AV/DUAL`：在 min-lb 开节点上尝试证书；
- `BBF`：展开 min-lb 开节点；
- `MCTS`：从 UCT 选择的节点做一次 rollout，更新上界。

上下文特征：

```text
φ(σ,H) = [1,
          prec_density,          # R 诱导子图的边密度
          slack_ratio,           # (mH-P(R))/(mH)
          pmax_ratio,            # max p_i / H
          machine_imbalance,     # (max A - min A)/max(1,max A)
          forced_frac,           # |X_full|/|R|
          log(1+E_phase_full)]   # 全窗口的相变分数
```

奖励：

```text
r_t = min(1, ( (L_t - L_{t-1}) + (U_{t-1} - U_t) ) / (G_0 · max(1, c_t))),
G_0 = U_0 - L_0.
```

`c_t` 用确定性操作计数（窗口数、子集和 bitset 字数、最小割调用数）；实现中可用归一化 wall-clock。奖励只计算**已验证**的间隙下降：失败或 checker 拒绝的证书不改变 `L`，奖励为 0。

### 6.2 LinUCB

对每个 arm `a` 维护

```text
A_a = λI + Σ_{s: a_s=a} φ_s φ_s^T
b_a = Σ_{s: a_s=a} r_s φ_s
θ_a = A_a^{-1} b_a
UCB(a,φ) = θ_a^T φ + α sqrt(φ^T A_a^{-1} φ)
```

选择

```text
a_t = argmax_{a∈A_allowed(t)} UCB(a,φ_t).
```

每个 arm 先各跑一次初始化；之后按 UCB 选择。对非平稳的 B&B 上下文，可以用滑动窗口或折扣 `A_a←γA_a+φφ^T`；本轮理论假设平稳，折扣版留作工程选项。

### 6.3 安全护盾与公平性

```text
函数 SHIELD(a, t, F, U, L)
────────────────────────────────────────────────
1  if t mod K_fair = 0:
2      return BBF(argmin_{v∈F} LB(v))
3  if t mod K_fair = 1 and U > L:
4      return MCTS
5  if a ∈ {ER,DFF,PC,AV,DUAL}:
6      if F=∅ or U≤L: return BBF_or_STOP
7      return a
8  return a
```

- 每 `K_fair` 步强制一次 BBF，保证前沿推进；
- 每 `K_fair` 步强制一次 MCTS（当 `U>L`），保证上界侧有机会改进；
- 证书动作只作用于开节点；失败不剪枝；
- 若 bandit 选择证书但当前没有可用节点，护盾退回 BBF；
- 默认 `K_fair=8`，要求 `K_fair≥4`，否则护盾会占满所有步骤，证书 arm 没有机会运行；
- 被护盾覆盖的步骤只更新护盾统计，不更新 bandit 的 `A_a,b_a`；否则定理 3 的平稳 i.i.d. 假设被破坏。

**公平性引理**：若预算无限，每个开节点最终都会被展开或剪枝。

**证明（草图）**：护盾每 `K_fair` 步对 min-lb 开节点执行一次 BBF；BBF 展开该节点，生成有限个子节点。搜索树有限，证书动作只会删除节点，MCTS 不改变前沿。因此前沿最终为空，或某个节点的 LB 达到 `U` 而被剪枝。证毕。

### 6.4 遗憾界

**定理 3（LinUCB 遗憾）**：假设上下文 `φ_t` 独立同分布于 `D`，`||φ_t||≤1`；对每个 arm `a`，`E[r_t(a)|φ_t]=θ_a^T φ_t`，`||θ_a||≤1`；噪声有界。则 LinUCB 在 `T` 次拉取后的累积遗憾满足

```text
Regret(T) ≤ κ·d·sqrt(T log(T/δ))
```

以至少 `1-δ` 的概率成立，`κ` 为通用常数。于是平均奖励以
`O(d sqrt(log T / T))` 收敛到最佳线性策略。

**备注**：

- 护盾限制动作集；遗憾是相对于“护盾允许的最佳线性策略”。相对于无护盾最优，护盾强制 BBF/MCTS 可能带来 `O(T/K_fair)` 的线性项；这是为了保证公平性/完备性付出的代价。若把 BBF/MCTS 视为必要动作，则遗憾界是相对于最佳护盾策略的。
- 定理假设平稳上下文；真实 B&B 的上下文分布随搜索深度变化。折扣 LinUCB 是对策，但没有同样的遗憾保证。这是本轮的一个已知理论缺口。

**推论（平均情况 anytime 间隙）**：设最佳护盾策略的期望每步奖励为 `r*`，初始间隙为 `G_0=U_0-L_0`。则 `T` 步后的期望间隙至多

```text
G_0 - T·r* + κ·d·sqrt(T log T).
```

这是遗憾界的直接推论；它把“学习控制器”与“anytime 间隙”连接起来。

### 6.5 bandit 实验（诚实版）

**设置**：600 个状态，来自三个家族各 200 个：

- 随机 DAG：`n∈{8,9,10}`，边概率 `{0.2,0.35,0.5}`；
- 两层 DAG：前半到后半边概率 0.6；
- 无依赖：`E=∅`。

`m=2`，`P∈{10,20}`；随机调度前缀；`H=U-1`，`U` 由 greedy list schedule 给出；枚举事件窗口；四个 arm 的精确结果如下（成功率）：

| 家族 | ER | DFF | PC | AV | 任一成功 |
|---|---:|---:|---:|---:|---:|
| 随机 DAG | 0.06 | 0.49 | 0.07 | 0.17 | 0.60 |
| 两层 DAG | 0.04 | 0.09 | 0.09 | 0.38 | 0.41 |
| 无依赖 | 0.01 | 0.00 | 0.01 | 0.62 | 0.62 |

策略比较（成本单位：窗口数或 `|X|` 的累计操作数；学习策略为 10 轮打乱后的平均，固定顺序与 oracle 为确定性单次）：

| 策略 | 成功率 | 平均成本 |
|---|---:|---:|
| v0.3 顺序 ER→DFF→PC→AV | 0.545 | 26.8 |
| 最佳固定顺序 DFF→AV→PC→ER | 0.545 | 19.9 |
| LinUCB | 0.545 | 20.9 |
| 表格 UCB（密度/松弛/不平衡分桶） | 0.545 | 19.6 |
| oracle（知道哪个 arm 成功） | 0.545 | 3.36 |

实验用 `success - γ·min(1,c/B)` 作为奖励代理（`γ=0.02`，`B=50`），不是 §6.1 的间隙下降奖励；窗口级状态没有完整的 B&B 间隙轨迹。动作集也只含四个证书 arm；`DUAL/BBF/MCTS` 需要完整 B&B 才能模拟，未进入这个合成实验。

**解读**：

1. bandit 学会了匹配最佳固定顺序，但没有显著超过它；表格版只把成本从 19.9 降到 19.6。
2. oracle 的 3.36 说明“知道哪个 arm 会成功”仍然有巨大价值；廉价特征不足以预测成功。
3. 因此，本轮不把 RL 层当作性能突破，而把它当作**安全、可移植、可解释的控制层**：它保证不破坏正确性，能在不同家族间自动调整，并为未来的成功预测器留出接口。
4. 主要性能增益来自 AVAIL 和 PHASE-RANK，而不是 bandit。这是必须诚实报告的负结果。

## 7. 主循环 X-DUB/OL

```text
算法 X-DUB/OL(G,p,m,B)
────────────────────────────────────────────────
1  (lo,q,L0) ← PRECOMPUTE(G,p,m)
2  π0,U0 ← CP-LIST-SCHEDULE(G,p,m)
3  best ← (U0,π0);  U ← U0
4  root ← NEW-NODE(σ0=(∅,0^m,⊥))
5  root.lb ← LB-X4(root,U)
6  F ← {root};  L ← max(L0,root.lb)
7  bandit ← INIT-LINUCB(d)
8  for t=1,2,...,B do
9      if F=∅ then L←U; break
10     if L≥U then break
11     φ ← CONTEXT(F,U,L)
12     a ← BANDIT-CHOOSE(bandit,φ)
13     a ← SHIELD(a,t,F,U,L)
14     if a ∈ {ER,DFF,PC,AV,DUAL}:
15         v ← argmin_{w∈F} LB(w)
16         cert ← CERTIFY-ARM(a,v,U-1)      # PHASE-RANK 在内部排序窗口
17         if cert is valid:
18             prune v; L ← max(L,U)
19         reward ← REWARD(ΔL,ΔU,cost,G_0)
20     elif a = BBF:
21         BBF-STEP(root)                    # 展开 min-lb 开节点
22         reward ← REWARD(ΔL,0,cost,G_0)
23     else:  # MCTS
24         MCTS-STEP(root)                   # UCT + rollout，更新 U
25         reward ← REWARD(0,ΔU,cost,G_0)
26     BANDIT-UPDATE(bandit,a,φ,reward)
27     UPDATE-FRONTIER(root)
28     L ← max(L, MIN-LB(F))
29     if t mod T_scan = 0:
30         L ← max(L, SCAN-BOUNDS(F,U))      # 对前沿节点尝试更低的 H
31     ADAPT-CERT-BUDGETS()                  # 可选的失败加倍/衰减
32 end for
33 if F=∅ or L≥U:
34     PROOF ← BUILD-PROOF(root,U)           # 包含 PACK-CORE-AVAIL 叶子
35 return best,L,U,gap=(U-L)/max(1,L),PROOF
```

其中：

```text
LB-X4(σ,U) =
  L ← max(C(σ), LB-CP(σ), LB-W(σ))
  if L ≥ U: return L
  if CERTIFY-AVAIL(σ,U-1) succeeds: return U
  return L

REWARD(ΔL,ΔU,cost,G_0) = min(1, (ΔL+ΔU)/(G_0·max(1,cost)))
```

`SCAN-BOUNDS(F,U)` 对每个前沿节点尝试比 `U-1` 更低的 `H`，更新该节点的 `LB`，然后返回 `min_{v∈F} LB(v)`；它是前沿上的全局下界，不是单个节点的界。它不剪枝，只收紧 anytime 区间。`ADAPT-CERT-BUDGETS` 是本轮保留的可选工程层：若 AVAIL/PC 连续失败，就降低 `k_core` 或切换到 DFF/DUAL；若成功，就恢复默认预算。它不是正确性的一部分。

## 8. 证明树与 checker

### 8.1 节点类型

在 v0.3 的节点类型上新增：

```text
PACK-CORE-AVAIL: 附带 (H, a, b, X, π)
```

其中：

- `H ≥ U-1`（剪枝时刻）；
- `X⊆R(σ)`；
- `π ∈ {TRIVIAL, AGG, DFF(k), SUBSET, PACK-BB}`。

它替代 v0.3 的 `PACK-CORE` 叶子；其他节点类型不变。

### 8.2 checker 规则

```text
CHECK-PACK-CORE-AVAIL(σ,H,a,b,X,π):
1  验证 H ≥ U-1 且 b > a
2  从 σ 和原 DAG 重算 lo_i, q_i, A_k
3  对每个 i∈X:
4      验证 i∈R(σ)
5      验证 lo_i ≥ a
6      验证 H - q_i ≤ b
7  caps_k ← max(0, b - max(a, A_k)), k=1..m
8  if π = TRIVIAL:
9      验证存在 i∈X 使 p_i > max_k caps_k
10 elif π = AGG:
11     验证 P(X) > Σ_k caps_k
12 elif π = DFF(k):
13     验证 C_min = min_k caps_k 且 Σ_{i∈X} u_k(p_i;C_min) > m
14 elif π = SUBSET:
15     验证 m=2
16     设 caps=(c_0,c_1)，按 c_0≥c_1 排序
17     验证 P(X) ≤ c_0+c_1
18     验证 SUBSET-SUMS(X, limit=c_0) ∩ [max(0,P(X)-c_1), min(c_0,P(X))] = ∅
19 elif π = PACK-BB:
20     递归验证异构装箱搜索树：
21       每个内部节点枚举第一个未分配工件的所有可行箱子
22       （或第一个箱子的所有极大装载），子节点覆盖所有可能性；
23       每个叶子都超容量；相同剩余容量的箱子去重不丢解
24 else: reject
25 接受（H 不可行）
```

### 8.3 独立性

- `lo_i,q_i,A_k` 由 checker 从 `σ` 和原 DAG 重新计算，不信任搜索器的缓存；
- `X` 的强制性逐项验证；
- `caps` 由 checker 重算，不信任求解器；
- 装箱证据局部验证：AGG/DFF 是 `O(|X|)`；SUBSET 是 bitset DP 重算；PACK-BB 是递归检查；
- 不需要信任“窗口是如何排序的”“bandit 为什么选这个 arm”“相变分数是多少”。

### 8.4 证明树可靠性

**定理 4（证明树可靠）**：若 `CHECK(root)` 通过，则 `U=OPT`。

**证明**：对树自底向上归纳。`TERMINAL` 附可行调度，`Cmax≥U`；`PRUNED-DUAL` 由 v0.2 的对偶引理没有更优完成；`PACK-CORE-AVAIL` 由定理 1 没有 `Cmax≤H` 的完成，而 `H≥U-1`，所以没有 `Cmax<U` 的完成；`EXACT` 由精确子求解器；`EXHAUSTED` 的所有动作都被子节点或已剪枝动作覆盖。归纳到根，根没有 `Cmax<U` 的完成；incumbent 给出可行 `U`，故 `U=OPT`。证毕。

## 9. 正确性论证汇总

### 引理 1（强制在窗口内）

已证于 3.2。

### 引理 2（机器容量）

已证于 3.2。

### 定理 1（AVAIL 可采纳）

已证于 3.2。

### 定理 2（AVAIL 支配 PC）

已证于 3.3。

### 引理 3（两箱异构判据）

已证于 3.4。

### 引理 4（PHASE-RANK 安全）

PHASE-RANK 只改变窗口测试顺序；若它返回证书，证书由定理 1 保证可靠；若返回 `FAIL`，不改变 `L`。因此排序错误不影响正确性。

**证明**：算法只在 `EXACT-ARM` 返回 `INFEASIBLE` 时构造证书；证书的可靠性由定理 1（AVAIL）、v0.3 的 ER/DFF 引理或对偶引理保证。`FAIL` 只表示“本预算内没找到”，不会导致剪枝。证毕。

### 引理 5（护盾公平性）

已证于 6.3。

### 引理 6（bandit 安全）

bandit 只选择动作；证书必须通过 checker；失败不改变 `L`；BBF/MCTS 不删除节点。因此 bandit 的任何内部状态都不会破坏 `L≤OPT≤U`。

### 定理 5（任意时刻区间）

在 `X-DUB/OL` 运行的任意时刻，

```text
L ≤ OPT ≤ U.
```

**证明**：`U` 来自可行调度（CP 或 rollout），故 `OPT≤U`。`L` 是 `L0`、前沿 `LB-X4`、`SCAN-BOUNDS` 的最大值；每个分量由定理 1/v0.3 引理可采纳；前沿覆盖性给出 `L≤OPT`。证毕。

### 定理 6（精确模式终止即最优）

若 `X-DUB/OL` 因 `F=∅` 或 `L≥U` 终止，则 `U=OPT`。

**证明**：若存在 `Cmax<U` 的调度，由动作覆盖性和前沿覆盖性，它必须经过某个开节点 `v`，且 `LB-X4(σ_v,U)≤Cmax<U`。这与 `F=∅` 或 `L=min_{v∈F}LB-X4≥U` 矛盾。故不存在更优调度；结合 incumbent 可行性，`U=OPT`。证毕。

### 定理 7（有限完备性）

搜索树有限；`X-EXACT` 的每次 BBF 前进一个任务；护盾每 `K_fair` 步强制一次 BBF；证书只删除节点。因此若预算无限，前沿最终为空或 `L≥U`。最坏情况时间复杂度指数；这是 NP-hard 问题的预期行为。bandit 的不完美只影响时间，不影响完备性。

### 定理 3（LinUCB 遗憾）

已述于 6.4；证明是标准 LinUCB 的置信椭球论证，此处不重复。

## 10. 复杂度分析

### 10.1 单次操作

- **预处理**：拓扑排序 + head/tail，`O(n+|E|)`。
- **`L0`**：`O(n+|E|)`。
- **窗口枚举**：`O(n²)` 个事件窗口；每个 `O(n)` 计算强制集，朴素 `O(n³)`；可用离线排序/二维前缀降到 `O(n²)`（精确子集和另算）。记 `T_win(n)`。
- **`E_phase`**：每窗口 `O(|X|)`。
- **m=2 精确测试**：bitset `O(|X|·C/word)`；若 `C` 很大而 `|X|` 小，用 meet-in-the-middle `O(2^{|X|/2})`。
- **m>2 `PACK-BB`**：最坏 `O(m^{|X|})`，只在小核 `|X|≤k_core` 上运行。
- **`SHRINK-CORE`**（可选，只用于缩小证书）：`O(|X|)` 次装箱测试。
- **对偶**：`K_dual` 次最小割；`T_cut(n,H)` 同 v0.3。
- **BBF 单节点**：`O(T_win + T_avail + b(n+m))`，`b=m·|Ready|`。
- **MCTS rollout**：`O(n(n+|E|))`。
- **LinUCB 单步**：`O(K·d²)`，`K=7`，`d=8`；相对证书成本可忽略。

### 10.2 总计

设 `N` 为物化节点数，`B` 为总预算：

```text
时间: O( N·(T_win + T_avail + b(n+m)) + B·n(n+|E|) + B·K·d² )
空间: O( N(n+m) + |Π|·(n+core_size) + K·d² )
```

最坏情况：

```text
N = O((m·n)^n)
T_avail = O(T_win + |X|·C/word)       # m=2
        = O(T_win + m^{k_core})       # m>2 小核
```

- 认证总时间仍最坏指数；v0.4 没有改变 `P|prec|Cmax` 的最坏复杂度。
- AVAIL 的单次成本与 PC 同阶；端到端节点数下降可以抵消额外常数（见 11.4）。
- 证书检查：AGG/DFF 是 `O(n+|E|+|X|)`；SUBSET 是 `O(|X|C/word)` 或 `O(2^{|X|/2})`；PACK-BB 与搜索树大小成正比。
- PHASE-RANK 的排序是 `O(n² log n)` 每节点；可用堆/增量维护优化，但本轮不做。

### 10.3 成本控制

- 先用 `L0`/deadline；不足才跑 AVAIL。
- 先用 `E_phase` 排序；`E_phase` 很大的窗口直接跳过精确测试（`B_cheap` 预算）。
- `k_core` 默认 8–12；超过就退回 DFF/DUAL。
- 对偶结果按状态哈希缓存；`U` 下降后旧证书仍有效。
- AVAIL 证书按 `(σ,H,a,b,X,caps)` 缓存；同一 `(a,b,X)` 在不同 `H` 上可复用，但 `H` 变大时强制集可能变小，需要重新验证。
- bandit 用滑动窗口/折扣防止早期统计支配后期；护盾保证公平。

## 11. 实验设计与本轮结果

### 11.1 AVAIL 状态实验

**设置**：

- `n=9`，`m=2`，`P=10`，随机 DAG 边概率 0.35；
- 随机调度一个前缀，得到状态 `σ`（`A_k` 可能非零）；
- `H=C(σ)+U{0,...,10}`；
- 枚举全部事件窗口，m=2 精确子集和；
- 对每个状态，记录 PC 和 AVAIL 是否找到至少一个不可行窗口。

**结果**（1772 个非空状态）：

| 指标 | 数量 |
|---|---:|
| PC 找到不可行窗口 | 1397 |
| AVAIL 找到不可行窗口 | 1457 |
| 存在 AVAIL-only 不可行窗口 | 1270 |
| 存在 PC-only 不可行窗口 | 0 |

**解读**：

- 支配关系成立：没有 PC 更强的情况。
- AVAIL 在 72% 的状态上至少有一个窗口严格更强；这是一个状态层的强证据。
- 这是下界强度实验，不是端到端时间；11.4 给出节点数。

### 11.2 相变标定

见 4.3 的两张表。补充说明：

- 这是合成子集实验，不是完整调度实例；它验证的是 `BP(X,2,C)` 的子集和相变。
- 对 `k≤4`，局部 CLT 可能不准；算法在这些小集合上直接跑精确子集和，不用预测分数做剪枝。
- 对非均匀工时（例如大量相同工时），公式可能偏离；bandit/精确测试会纠正，但排序可能变差。这是风险 3。

### 11.3 PHASE-RANK 窗口选择

见 5.4 的表。补充：

- “有核实例”是 oracle 至少找到一个不可行窗口的实例；不是所有实例都有核。
- 两者在“有核”实例上的成功率都是 100%，因为最终会扫描所有窗口；PHASE-RANK 的价值是平均测试次数减半。
- 这个实验没有比较完整证书组合（ER/DFF/DUAL），只比较窗口排序。

### 11.4 端到端 B&B 节点数

**设置**：

- `n=7`，`m=2`，`P=10`，随机 DAG 边概率 0.3，共 12 个实例；
- best-first B&B，动作空间 `(i,k)`，greedy list schedule 给 `U`；
- 两个变体：`L0+PC` 与 `L0+AVAIL`；同一动作模型、同一贪心上界、同一节点上限 50,000；
- 两版返回的 `OPT` 完全一致（这是正确性的 sanity check）。

**结果**：

| 实例 | PC 扩展节点 | AVAIL 扩展节点 |
|---:|---:|---:|
| 0 | 1305 | 97 |
| 1 | 3447 | 53 |
| 2 | 8719 | 18 |
| 3 | 12421 | 1 |
| 4 | 0 | 0 |
| 5 | 576 | 29 |
| 6 | 0 | 0 |
| 7 | 2 | 2 |
| 8 | 0 | 0 |
| 9 | 0 | 0 |
| 10 | 0 | 0 |
| 11 | 0 | 0 |
| **合计** | **26,470** | **200** |

- 6 个实例在根节点就被 `L0` 闭合（0 节点），两种变体相同；另有 1 个实例两版都只展开 2 个节点；差异集中在其余 5 个实例。

- **边界**：样本只有 12 个 n=7 实例；这不是 benchmark，不能外推到 PSPLIB/大 n。它只证明“状态层下界改进可以转化为搜索树节点下降”这一因果链。

### 11.5 bandit 混合家族实验

见 6.5 的两张表。补充：

- 成本单位是窗口数/`|X|` 累计操作数，不是 wall-clock；不同实现的绝对成本会变。
- LinUCB 的成功率与最佳固定顺序相同但成本略高（20.9 vs 19.9）；表格 UCB 成本 19.6，仅略低；oracle 仍远低（3.36）。这说明“arm 选择”不是当前瓶颈，**成功预测**才是。

**P1（checker 对拍）**：500 个 `n≤9`、`m∈{2,3}` 的随机实例；独立实现 `CHECK-PACK-CORE-AVAIL`，与主算法隔离；目标零假证书。

**P2（m>2 异构装箱）**：实现 `PACK-BB` 的异构容量版本和检查器；在 `m=3,4` 上测 AGG/DFF/PACK-BB 的覆盖率和证书大小。

**P3（端到端 anytime）**：`n=10..20`，`m=2,3`，比较 v0.3、AVAIL-only、AVAIL+PHASE、完整 X-DUB/OL 的 anytime 曲线、节点数、证书检查时间；加入 PSPLIB/fork-join。

**P4（bandit 消融）**：LinUCB vs 表格 UCB vs 固定顺序；加入“成功预测器”特征（例如最佳窗口的 DFF 分数、相变分数、对偶价格峰值），看能否缩小 oracle 差距。

**P5（相变边界）**：非均匀工时、相同工时、重尾工时；验证 `E_phase` 的排序是否仍然有效；必要时加入有限样本修正。

**P6（非平稳 bandit）**：折扣 LinUCB / 滑动窗口；比较节点流上的 regret 代理指标；目前没有理论保证。

## 12. 已知风险

1. **AVAIL 只在内部状态严格更强**：根节点 `L_AV=L_PC`，所以它不能改善根界。若 B&B 在根节点就闭合（如 11.4 的 6/12 实例），AVAIL 没有收益。缓解：只在需要展开的节点上计算；与 PHASE/对偶组合。

2. **相变公式是渐近的**：局部 CLT 对小 `|X|`、相同工时、重尾分布可能不准；预测分数可能把可行窗口排在前面。缓解：小集合直接精确测试；分数只用于排序；保留 `B_cheap` 预算；bandit 校准。

3. **bandit 的实证增益有限**：在 600 个混合状态上，它只匹配最佳固定顺序，远未达到 oracle。廉价特征不足以预测 arm 成功。缓解：把它定位为安全控制层；下一步加入成功预测器/多保真筛选；不要把它当作性能卖点。

4. **bandit 的理论假设偏强**：LinUCB 遗憾界假设平稳 i.i.d. 上下文；真实 B&B 上下文随深度变化。折扣版没有同样的保证。缓解：报告为工程选项；主线正确性不依赖它。

5. **m>2 的精确 AVAIL 未实现**：异构装箱 B&B 和检查器只在小核上可行；DFF 用 `C_min` 是保守的，可能弱很多。缓解：先做 m=2；m>2 用 AGG/DFF/对偶回退；下一轮实现 PACK-BB。

6. **端到端实验规模小**：n=7、12 个实例，不能说明大 n/PSPLIB 的表现；节点数下降可能被 AVAIL 的单节点成本抵消。缓解：下一轮跑 anytime 曲线和规模实验；报告单节点成本。

7. **证书检查不再总是多项式**：m=2 子集和是伪多项式（或 MITM 指数于 `|X|`）；m>2 的 PACK-BB 可能指数。v0.3 的“多项式可检查”在 AVAIL 上退化为“核规模参数化可检查”。缓解：默认 AGG/DFF；只在 `|X|≤k_core` 时用 SUBSET/PACK-BB；明确论文表述。

8. **PHASE-RANK 的排序成本**：每节点 `O(n² log n)` 排序，窗口多时可能比 v0.3 的启发式贵。缓解：增量维护/堆；只对前 `B_cheap` 个窗口精算；大 n 用束搜索。

9. **AVAIL 的强制集仍然只收集“完全在窗口内”的任务**：部分重叠、跨窗口的顺序空闲仍然看不见。随机 DAG 的剩余间隙可能来自这些结构；AVAIL 只能补机器可用时间，不能补所有时间冲突。缓解：与对偶/流证书组合；不要声称 AVAIL 能闭合所有 precedence-heavy 实例。

10. **证明树/checker 工程复杂度**：新增 AVAIL 节点、异构 caps 重算、SUBSET/PACK-BB 递归检查；一个错误的容量或区间判据会接受假最优。缓解：checker 独立实现；穷尽对拍；默认只用 AGG/DFF；核大小上限。

11. **模型假设**：确定性、同构机器、整数工时、无 release/准备时间；随机工时下 `lo/q` 和 AVAIL 的可采纳性不直接成立。缓解：明确边界；随机工时作为下一轮扩展。

12. **最坏情况复杂度没有改善**：B&B 仍指数；AVAIL/PHASE/bandit 都是常数或参数化改进。v0.4 的贡献是“更强的状态层证书 + 有概率解释的窗口排序 + 安全的在线控制”，不是新的最坏情况界。

---

## 13. 一句话最大风险

**当前方案最大的风险是：AVAIL 只在内部状态严格强于 PC，而 bandit 在廉价特征下的增益可能很有限；在大型 precedence-heavy 实例上，新增的异构装箱与控制器开销可能抵消节点数下降。**
