# 第 1 轮（灵感循环 v2：「伦理审查」×「UniBot世界挑战赛」）—— 从「排行榜优化」到「可审查的竞赛行为」

> 承接 research.md 已有的 UIP-01~10（v1）：上一版把问题定义为「如何在远程 API 内把成功率与步骤分做高」，旗舰是常识进度验证器驱动的滚动重试。本轮换一个更上位的问题：**哪些行为即使能提高分数，也不应被允许？哪些行为没有直接分数，却决定一个 submission 是否可信、可复现、可追责？** 这不是给方案加一层「安全装饰」，而是改变优化问题的结构：官方榜单是**可补偿的标量**，伦理审查是**非补偿的程序**；本轮把后者编译成运行时可执行的契约，再在前者上求最优。

## 0. 先给直觉：IRB 不做加权平均，排行榜却做

伦理审查（IRB / 研究伦理）最反直觉的地方是：它**不做风险-收益的加权平均**。再高的预期收益，也不能抵消「没有知情同意」「伤害弱势群体」「绕过独立审查」这些硬项；审查是逐项合取（∧），任一项失败即否决。相反，UniBot 排行榜是一个典型的可补偿目标：平均成功率 + 步骤分，强任务补偿弱任务，高步骤分补偿低成功率，一次「幸运的成功」还可能掩盖一次「危险的近失」。

把两者放在一起，得到一个尖锐的诊断：**当竞赛只奖励可补偿的分数时，竞争压力会系统性地选择冒险行为**——忽略罕见但不可逆的任务、忽略人类干扰轴、把延迟和动作规律性「调」到可信度检查的边缘、在公开榜单上反复试探直到找到过拟合点。这不是某个选手的道德问题，而是**目标函数的结构问题**：安全与诚实是公共品，纯排名竞争会供给不足。伦理审查恰好提供了缺失的结构：非补偿、程序化、可审计、持续复审。

本文的「伦理审查」是**方法论借喻**：借用 IRB 的程序结构（协议、同意/授权、独立审查、持续复审、不良事件），把它映射到竞赛 submission 的运行时治理；不声称替代任何真实 IRB、法律审查或机器人安全认证（ISO 10218 / TS 15066）。

## 1. 直觉之后：把「审查」拆成可执行部件

IRB 的六个程序部件可以一一映射到远程 API 选手能控制的东西：

| IRB 程序 | 机器人竞赛中的对应物 | 选手权限内的实现 |
|---|---|---|
| 研究协议（protocol） | 任务合同：范围、风险上限、可逆性、证据要求 | `ERC` 契约编译器 |
| 知情同意 / 授权 | 数据与运行范围的授权；无法在评测中弹窗征求同意 | 数据来源审计 + 运行范围门（不做虚假的「运行时同意」） |
| 独立审查 | 与策略不同源的红队/评审器 | 独立风险模型 + 红队测试集 + 证据账本 |
| 风险-收益评估 | 成功率/步骤分 vs 不可逆伤害 | 非补偿动作盾 + 词典序目标 |
| 弱势群体保护 | 稀有/脆弱/人类邻近的任务层 | 最差组约束 + 人类邻近包络 |
| 持续复审 / 不良事件 | 在线监测、近失报告、模型更新前复审 | `AET-CR` 状态机 + 影子模式 |

关键洞见：**远程 API 里唯一能执行伦理审查的地方，就是 `get_action` 的动作选择函数，以及随附的证据链。** 选手碰不到电机、ROS、急停；但可以决定「给不给这个动作」、可以拒绝、可以退回安全动作、可以记录为什么。伦理审查因此不是外部文档，而是**运行时的可执行约束**。

## 3. 两个灵感词的交叉解读

1. **伦理审查**：核心不是「更保守」，而是**非补偿 + 程序正当 + 持续复审**。把「安全」从加权项提升为否决项；把「审查」从一次性文档变成状态机；把「弱势」从模糊修辞变成最差组约束；把「不良事件」从事故后追责变成在线触发。
2. **UniBot 世界挑战赛**：这是一个**全球、真机、多任务、隐藏分布**的竞赛。全球意味着不同实验室的安全规范与数据来源不同；真机意味着错误不可逆；隐藏分布意味着公开榜单不能代表真实泛化；排行榜反馈意味着过拟合诱因。四者叠加，使「安全赛跑到底」（race to the bottom）成为结构性风险：**如果只排名分数，忽视风险策略会系统性地占优。**
3. **交叉点**：伦理审查不是「给研究加限制」，而是一种**在不可约不确定性与价值冲突下做决策的设计模式**。在机器人竞赛里，它自然落成三个技术对象：**契约（contract）**、**盾（shield）**、**账本（ledger）**。

## 4. 瓶颈假设

- **H1（平均暴政）**：官方平均成功率会掩盖最差任务/最差泛化层的失败；隐藏测试恰恰更接近最差组。只优化平均，等于把风险外部化给少数任务。
- **H2（标量不可编码非补偿）**：任何 `score - λ·harm` 都把安全变成可交易项；λ 无法从公开数据唯一确定，且随分布漂移。必须用硬约束/词典序，而不是把安全塞进一个加权和。
- **H3（远程 API 的「人类在环」不可验证）**：选手无法证明「有人监督」；能证明的只有运行时的拒绝、退避、暂停与日志。伦理审查必须落在可观测的动作与证据上。
- **H4（榜单过拟合）**：反复用排行榜反馈调参等价于多重检验；不预注册、不控制 α，就会把公开榜单的噪声当成进步。
- **H5（安全过滤的分数代价）**：过严的盾会杀死步骤分；过松的盾没有保证。需要**共形风险控制 + 保分 fallback**，把「拒绝」设计成仍能拿部分步骤分的动作。
- **H6（不可逆动作的次序）**：倒药、插针、插网线等动作一旦执行就难以回退；应先做可逆子目标、积累证据，再执行不可逆子目标。
- **H7（竞争性风险外部化）**：如果赛制不惩罚危险近失，单个队伍的最优策略是冒险；这是**公地悲剧**，需要非补偿协议或独立审查来内部化外部性。

## 5. 候选创新点：EIP-01~09

（完整表、伪代码、实验设计见产物区。）

- **EIP-01 ERC-C**：伦理审查契约编译器——把任务、语言、步骤分、泛化轴编译成 `(scope, risk_max, reversibility, evidence, stop)` 契约。
- **EIP-02 NCAS**：非补偿性动作盾——在 `get_action` 内对候选动作块做硬过滤；无安全候选时退到保分 fallback，而不是继续执行。
- **EIP-03 WGS**：最差组正义选择——用分层下置信界做模型选择，先满足每组下限，再最大化平均分。
- **EIP-04 HPSE**：人类邻近安全包络——检测人/外来物，按距离限速、暂停、退避；直接服务人类干扰轴。
- **EIP-05 RASS**：可逆性优先子目标调度——先可逆、后不可逆；把「证据够了再承诺」写进调度。
- **EIP-06 ELRC**：证据账本与运行证书——哈希链记录每步观测、动作、门控、事件；支持复现与追责。
- **EIP-07 PBAS**：预注册盲选与序贯 α 花费——先注册模型选择规则，再有限次查询榜单；抑制过拟合。
- **EIP-08 AET-CR**：不良事件分类与持续审查——近失/轻微/重大/严重/灾难分级，触发收紧、暂停、复审。
- **EIP-09 DPC**：数据来源与同意审查——数据集许可、旁观者隐私、示范者授权、模型卡；训练/治理侧。

**旗舰点**：EIP-01+02 合成的 **ERC-Shield**。理由：它不需要碰硬件、可以包住任何基座策略（包括 v1 的 UIP-01）、直接作用于高风险任务与人类干扰轴、并且天然产出可审计证据。它把「伦理审查」从一篇声明变成每次 `get_action` 都要通过的**否决层**。

## 6. 严谨定义（先直觉，后形式）

**直觉**：把每个动作想象成一张「许可申请」。契约规定哪些申请可以批、需要什么证据、什么情况下必须拒绝。盾是审批员；账本是审批记录；持续审查是事故后的执照复核。审批不是打分，不能「用高分买通否决项」。

**定义 1（风险格与可逆性）** 风险等级 `R={R0..R4}`，可逆性 `ρ ∈ {rev, costly_rev, irrev}`，序为 `rev ≺ costly_rev ≺ irrev`。动作风险元组 `r(a,o)=(level, ρ, affected, scope)`。

**定义 2（伦理审查契约 ERC）** `Π=(id, purpose, scope, A_affected, r_max, ρ_max, E_req, monitoring, stop, valid_until, signature)`。`scope` 是任务/物体/区域/时长的授权格；`E_req` 是必须提供的证据类型集合。

**定义 3（非补偿可接受性）** 
`Adm(a,o,Π) = Scope(a,o) ∧ r.level ≤ Π.r_max ∧ r.ρ ⪯ Π.ρ_max ∧ E_req ⊆ Evidence(o,a) ∧ ¬Stop(o)`。
非补偿公理：不存在权重 `w` 使 `Adm` 等价于 `Σ w_i ℓ_i ≥ θ`；任一硬项为 0 即 `Adm=0`。分数再高也不能补偿。

**定义 4（词典序目标）** 
`π* = argmax_{π ∈ Π_Adm} J(π)`，其中 `J(π) = (1_{Adm}, min_{s∈G_crit} SR_s(π), E[score(π)])` 按词典序比较；或等价的约束形式 `max E[score] s.t. P(violation)≤δ, min_s SR_s≥γ_s`。拉格朗日乘子只作为求解器，不作为目标定义。

**定义 5（共形风险控制盾）** 风险预测器 `V̂(o,a)`，门控 `g_λ=1[V̂≤λ]`；在校准集上选 `λ` 使 `P(V=1 | g_λ=1) ≤ α`；对每个关键层 `s` 用组条件阈值 `λ_s`；OOD 告警时自动降低 `λ`（更保守）。若 `g_λ` 拒绝全部候选，返回 `a_safe ∈ Fallback(o,Π)`，而不是执行最高分动作。

**定义 6（最差组正义）** 分层 `G = 任务族 × 泛化轴 × 风险层`。对每层 `s` 计算成功率下置信界 `L_s`（Clopper–Pearson）。`JusticeOK(π)=∀s∈G_crit: L_s(π)≥γ_s`。只在 `JusticeOK` 内按平均分选模型；若无可行模型，**不提交**或提交保守基线并记录原因。

**定义 7（证据账本与运行证书）** 每步记录 `rec_t = H(rec_{t-1} || H(o_t) || a_t || checks_t || decision_t || event_t)`；episode 结束签发 `J_run=(root, model_hash, data_manifest, contract_id, coverage, incident_log)`。账本不改变官方分数，但使「我们的策略做了什么、为什么」可复现、可审计。

**定义 8（持续审查状态机）** 状态 `{approved, tightened, suspended, withdrawn}`；事件 `{A0 近失, A1 轻微, A2 中等, A3 严重, A4 灾难, OOD_alarm, latency_drift}`。`A2` 收紧该动作类，`A3/A4` 暂停并触发复审；任何模型更新必须先在影子模式重跑红队与弱势层测试，通过后才回到 `approved`。

**定义 9（预注册与 α 花费）** 提交前固定 `(code_hash, data_manifest, model_selection_rule, metrics, stopping_rule)`；对 `K` 次榜单查询使用 `α_k` 且 `Σ α_k ≤ α`；报告所有查询，不选择性汇报。这把「榜单调参」从自由探索变成可审计的序贯实验。

## 7. 为什么它可能不是「只降分」

- **尾部风险**：伤害/碰撞/掉落导致 episode 归零，甚至损坏物体或机器人，连后续 episode 都受影响。用小幅成功率换取消除大尾部损失，期望分与 CVaR 都可能上升。
- **最差组**：隐藏测试更接近「未见物品/干扰物/人为干扰」的尾部；最差组约束直接把优化压力导向这些层。
- **人类干扰**：检测到人进入工作区时暂停/退避，避免碰撞；这比「继续执行然后失败/伤人」更可能保住 run。
- **保分 fallback**：拒绝不是「什么都不做」，而是退回到最近的已得分步骤或安全姿态，仍可保留步骤分。
- **可信度**：动作平滑、延迟稳定、重试有上限，降低触发可信度质疑的概率。
- **研究诚信**：预注册与盲选减少公开榜单过拟合，隐藏测试更稳。

**但要诚实**：如果隐藏测试不惩罚风险、官方规则也不要求伦理审查，那么硬约束就是纯成本；这正是本轮的最大风险。

## 9. 本轮最大风险

**一句话**：官方排名只奖励成功率与步骤分，而自设的硬性伦理门在规则不要求、隐藏测试也不惩罚危险行为时只会白白牺牲分数；若不能证明「安全约束在真实分布上同时改善尾部收益」，这套契约就会退化为昂贵的自我束缚。

| **EIP-04** | 人类邻近安全包络 HPSE | 伦理审查 + 挑战赛 | 人/外来物进入工作区时限速、暂停、退避 | ✅ 感知+动作层 | 误停降低效率 |
| **EIP-05** | 可逆性优先子目标调度 RASS | 伦理审查 | 先可逆、后不可逆；证据够了再承诺 | ✅ 推理调度层 | 违反任务自然顺序 |
| **EIP-06** | 证据账本与运行证书 ELRC | 伦理审查 + 挑战赛 | 哈希链记录每步决策，支持复现与追责 | ✅ 工程侧；延迟开销小 | 日志本身泄露/被篡改 |
| **EIP-07** | 预注册盲选与序贯 α 花费 PBAS | 伦理审查 + 挑战赛 | 先注册选模规则，再有限次查询榜单 | ✅ 流程侧 | 与赛制反馈节奏冲突 |
| **EIP-08** | 不良事件分类与持续审查 AET-CR | 伦理审查 | 近失/轻微/重大/严重/灾难分级触发收紧或暂停 | ✅ 运行时 | 事件定义主观、误报 |
| **EIP-09** | 数据来源与同意审查 DPC | 伦理审查 | 数据许可、旁观者隐私、示范者授权、模型卡 | 训练/治理侧 | 公开数据集信息不全 |

## 1. 旗舰点深潜：ERC-Shield（EIP-01 + EIP-02）

### 1.1 机制

`ERC-Shield` 是包在任意基座策略外面的**否决层**，不改基座权重、不碰执行层。每次 `get_action(obs)`：

1. **取契约**：按 `observation.language` + 任务名 + 当前子目标，取出 `ERC` 契约 `Π`。
2. **候选生成**：基座策略（pi0/ACT/SmolVLA/UnifoLM-VLA-0 或 v1 的 UIP-01）输出动作块 `A=(a_1..a_{T_a})`。
3. **风险预测**：独立风险模型对每个候选动作给出 `r(a,o)=(level, ρ, affected, scope)` 与伤害概率 `V̂`；输入含 4 路图像、双臂位姿、夹爪、语言、当前子目标。
4. **非补偿过滤**：按 `Adm(a,o,Π)` 逐项合取检查；一旦某个候选不安全，**截断动作块**，不执行该步及其后续。
5. **保分 fallback**：若整个块都被拒绝，返回 `Fallback(o,Π)`：保持姿态、沿来路退回、松开/重抓、退到最近已得分步骤、暂停等待人类离开。fallback 的目标是**保住已得步骤分**，不是「原地不动」。
6. **记录**：把观测哈希、动作、检查项、决定、事件写入哈希链账本；episode 结束签发运行证书。

### 1.2 与 v1 UIP-01 的差异

- UIP-01 是「**如何更可能成功**」：滚动验证子目标、重规划、重试。
- ERC-Shield 是「**即使更可能成功，也不能做**」：对动作做非补偿否决。
- 两者可叠加：UIP-01 生成候选与验证进度，ERC-Shield 在候选进入执行前做安全/范围/可逆性 veto。
- 关键差异不是「更保守」，而是**目标的词典序结构**：先 `Adm=1`，再谈成功率与步骤分；不允许用分数补偿硬项。

### 1.4 可行性、资源、步骤

- **可行性：高**。契约表可人工+LLM 辅助编写；风险模型可用小 VLM（Qwen2.5-VL-3B 级）+ 几何规则；共形校准只需离线数据；fallback 可用数据集中「安全恢复」片段或简单运动原语。
- **资源**：1 张推理卡可同时跑基座策略与小 VLM（或共享编码器）；32 份契约 2–3 天；离线回放 harness 1 周；红队测试集 3–5 天。
- **落地步骤**：
  1. 建立 32 任务的风险登记表（风险类、可逆性、受影响对象、stop 条件）。
  2. 定义 `ERC` schema 与版本化签名；把步骤分映射成子目标/证据要求。
  3. 训练或规则化风险预测器：人距、碰撞、滑移、接头方向、溢出、物体身份。
  4. 用公开数据 + 合成危险注入做组条件共形校准，选 `λ_s`。
  5. 实现 `get_action` 包装器：截断、fallback、日志。
  6. 在 `example_env.py` 桩与数据集回放上联调；测延迟与拒动作率。
  7. 红队：专门构造「高分但危险」的候选，测盾是否 veto。
  8. 影子模式跑 2–4 个真机任务，校准误杀率与步骤分损失。
  9. 预注册选模规则后提测。

### 1.5 主要风险

- **误杀（false positive）**：把安全动作判成危险，导致分数下降。用组条件阈值 + 置信度门限 + 影子模式校准。
- **漏杀（false negative）**：风险模型没识别出危险，给出虚假保证。用独立红队 + 保守默认 + 事件后收紧。
- **延迟**：小 VLM 每步推理可能超过预算。用异步/降频验证、只在关键子目标调用、缓存风险特征。
- **契约漂移**：任务/评分点/规则变化后契约过期。用版本号 + `valid_until` + 持续复审。

## 3. 形式化定义

### 定义 1（风险格）

风险等级 `R={R0,R1,R2,R3,R4}`，`R0` 最低。可逆性 `ρ ∈ {rev, costly_rev, irrev}`，序为 `rev ≺ costly_rev ≺ irrev`。动作风险元组：

```
r(a,o) = (level(a,o), ρ(a,o), affected(a,o), scope(a,o))
```

`affected` 包含人、旁观者、脆弱物体、硬件、网络/数据。`scope` 是动作作用的物体/区域/时长。

### 定义 2（伦理审查契约 ERC）

```
Π = (id, purpose, scope, A_affected, r_max, ρ_max, E_req,
     monitoring, stop, valid_until, signature)
```

- `scope`：任务/物体/区域/时长的授权格。
- `r_max`：允许的最高风险类；R4 任务通常 `r_max=R4`，但要求更强证据。
- `ρ_max`：允许的最差可逆性。
- `E_req`：执行前必须提供的证据集合，例如 `{target_identity, human_clear, force_below, orientation_ok}`。
- `stop`：立即停止的谓词列表（人进入、目标丢失、力超限、溢出、OOD 告警）。
- `signature`：契约版本与签署者，支持审计。

### 定义 3（非补偿可接受性）

```
Adm(a,o,Π) = Scope(a,o) ∧ level(a,o) ≤ Π.r_max
           ∧ ρ(a,o) ⪯ Π.ρ_max
           ∧ Π.E_req ⊆ Evidence(o,a)
           ∧ ¬Stop(o)
```

**非补偿公理（NC）**：不存在权重 `w` 使 `Adm` 等价于 `Σ_i w_i ℓ_i ≥ θ`；任一硬项为 0 即 `Adm=0`。特别地，成功率、步骤分、延迟优势都不能补偿 `human_clear` 或 `scope` 的失败。

### 定义 4（词典序目标）

```
π* = argmax_{π ∈ Π_Adm} J(π)
J(π) = ( 1_{∀ episodes: Adm=1},
         min_{s∈G_crit} SR_s(π),
         E[score(π)] )
```

按词典序比较：先满足全称可接受性，再最大化最差关键层成功率，最后最大化期望分数。等价的约束形式：

```
max E[score(π)]
s.t. P(violation) ≤ δ
     min_{s∈G_crit} SR_s(π) ≥ γ_s
```

拉格朗日乘子 `score - λ·violation` 只作为求解器；λ 必须由约束验证反推，不能把加权和当作目标本身。

### 定义 5（共形风险控制盾）

风险预测器 `V̂(o,a) ∈ [0,1]`，门控：

```
g_λ(o,a) = 1[ V̂(o,a) ≤ λ ]
```

在校准集 `D_cal` 上选 `λ`，使被放行样本中的伤害率满足：

```
P(V=1 | g_λ=1) ≤ α
```

对每个关键层 `s` 用组条件阈值 `λ_s`（组条件共形/风险控制）；当 OOD 分数超过阈值时，自动降低 `λ`（更保守）。若 `g_λ` 拒绝全部候选：

```
return a_safe ∈ Fallback(o,Π)
```

而不是执行最高分动作。`Fallback` 必须满足 `Adm`，并尽量保留步骤分。

### 定义 6（最差组正义）

分层 `G = 任务族 × 泛化轴 × 风险层`。对每层 `s`，用 `n_s` 次试验的成功数 `k_s` 计算 Clopper–Pearson 下界 `L_s`。模型可行域：

```
JusticeOK(π) = ∀s ∈ G_crit: L_s(π) ≥ γ_s
```

只在 `JusticeOK` 内按平均分选模型；若无可行模型，**不提交**或提交保守基线并记录原因。这把「弱势层」从口号变成可检查的约束。

### 定义 7（证据账本与运行证书）

每步记录：

```
rec_t = H( rec_{t-1} || H(o_t) || a_t || checks_t || decision_t || event_t )
```

Episode 结束签发：

```
J_run = (root, model_hash, data_manifest, contract_id,
         coverage, incident_log, code_hash, seed)
```

账本不改变官方分数，但使 submission 可复现、可审计、可追责。若官方不允许外传日志，则本地保存并在论文/技术报告中发布脱敏摘要。

### 定义 8（持续审查状态机）

状态 `S={approved, tightened, suspended, withdrawn}`。事件与转移：

```
A0 近失       : log, aggregate
A1 轻微       : log, aggregate
A2 中等       : S ← tightened, 复审动作类
A3 严重       : S ← suspended, 停止该动作类, 上报
A4 灾难       : S ← suspended, 全局停止, 冻结契约
OOD_alarm     : S ← tightened, λ ← λ/2, 降速
latency_drift : S ← tightened, 检查队列/批处理
```

任何模型/契约更新必须先在影子模式重跑红队与弱势层测试；通过才回到 `approved`，失败则 `withdrawn`。

### 定义 9（预注册与 α 花费）

提交前固定：

```
(code_hash, data_manifest, model_selection_rule, metrics, stopping_rule)
```

对 `K` 次榜单查询使用 `α_k`，满足 `Σ_{k=1}^K α_k ≤ α`；报告所有查询与失败尝试，不选择性汇报。这把「榜单调参」从自由探索变成可审计的序贯实验。

### 4.1 契约编译器

```python
@dataclass
class Contract:
    id: str
    task: str
    scope: set[str]
    r_max: int                 # 0..4
    rho_max: str               # rev / costly_rev / irrev
    evidence: set[str]
    stop: list[Callable]
    valid_until: float
    signature: str

class ERCCompiler:
    def __init__(self, registry):
        self.registry = registry          # 32 份人工签署的模板

    def compile(self, task, language, scoring_steps, axes):
        base = self.registry[task]
        return Contract(
            id=hash(task, language, base.version),
            task=task,
            scope=base.scope | parse_scope(language),
            r_max=base.r_max,
            rho_max=base.rho_max,
            evidence=base.evidence | parse_evidence(language),
            stop=base.stop,
            valid_until=base.valid_until,
            signature=base.signature,
        )

    def admits(self, a, obs, risk, contract):
        checks = {
            'scope': in_scope(a, obs, contract.scope),
            'risk': risk.level <= contract.r_max,
            'reversibility': rev_le(risk.rho, contract.rho_max),
            'evidence': contract.evidence <= evidence(obs, a),
            'not_stop': not any(s(obs) for s in contract.stop),
        }
        return all(checks.values()), checks
```

### 4.2 非补偿动作盾

```python
class ERCShield:
    def __init__(self, policy, compiler, risk_model, fallback, ledger, alpha=0.01):
        self.policy = policy
        self.compiler = compiler
        self.risk_model = risk_model
        self.fallback = fallback
        self.ledger = ledger
        self.alpha = alpha
        self.buf = []

    def reset(self):
        self.policy.reset()
        self.buf = []
        self.ledger.reset()

    def get_action(self, obs):
        contract = self.compiler.for_task(obs.task)
        if any(s(obs) for s in contract.stop):
            a = self.fallback.stop(obs, contract)
            self.ledger.log(obs, a, decision='stop', contract=contract)
            return a

        if not self.buf:
            chunk = self.policy.get_action(obs)       # (T_a, ...)
            rejected = None
            for a in chunk:
                risk = self.risk_model(obs, a)
                ok, checks = contract.admits(a, obs, risk, contract)
                if not ok:
                    rejected = (a, risk, checks)
                    break                            # 截断：不执行后续
                self.buf.append(a)

            if not self.buf:
                a = self.fallback.choose(obs, contract, rejected)
                self.ledger.log(obs, a, decision='fallback', contract=contract)
                return a

        a = self.buf.pop(0)
        self.ledger.log(obs, a, decision='ok', contract=contract)
        return a
```

### 4.3 共形阈值校准

```python
def calibrate_threshold(risk_scores, harm_labels, alpha):
    """Choose the largest pass threshold whose UCB(FNR) <= alpha."""
    best = None
    for thr in sorted(set(risk_scores)):
        passed = risk_scores <= thr
        n_pass = int(passed.sum())
        if n_pass == 0:
            continue
        missed = int(((harm_labels == 1) & passed).sum())
        if clopper_pearson_upper(missed, n_pass, alpha) <= alpha:
            best = thr
    return best if best is not None else -float('inf')


def calibrate_by_group(risk_scores, harm_labels, groups, alpha):
    return {s: calibrate_threshold(risk_scores[groups == s],
                                   harm_labels[groups == s], alpha)
            for s in set(groups)}
```

def select_model(models, strata, gamma, alpha=0.05):
    feasible = []
    for m in models:
        metrics = evaluate_stratified(m, strata)
        lcb = {s: clopper_pearson_lower(metrics[s].k, metrics[s].n, alpha)
               for s in strata}
        if all(lcb[s] >= gamma[s] for s in CRITICAL_STRATA):
            feasible.append((metrics.avg_score, m))
    if not feasible:
        return None                    # 不提交，或提交保守基线并记录
    return max(feasible, key=lambda x: x[0])[1]

| **E101** | 契约与风险预测在离线回放上可计算 | 无门控 vs 契约门控 | 门控精确率/召回、拒动作率、步骤分损失 | 召回 >0.9 时步骤分损失 <10% |
| **E102** | 非补偿盾+正义选择优于平均最优 | avg vs Lagrangian vs shield vs shield+justice | 公开/隐藏分数、最差层成功率、伤害率、CVaR | 隐藏最差层 +8–15 点（合成） |
| **E103** | 组条件共形在漂移下守住 α | 全局阈值 vs 组条件 vs OOD 降阈 | 每层 FNR、覆盖率、拒动作率 | FNR ≤ α，拒动作率可控 |
| **E104** | 人类包络降低碰撞/近失 | 无包络 vs 包络 | 碰撞/近失率、暂停延迟、恢复时间 | 近失显著下降，任务分损失小 |
| **E105** | 预注册抑制榜单过拟合 | 自由榜单搜索 vs 预注册+α 花费 | 隐藏测试退化、选择偏差、查询次数 | 隐藏退化显著减小 |
| **E106** | 可逆性优先减少不可逆早承诺 | 固定顺序 vs 风险拓扑序 | 不可逆早发率、部分得分 | 早发率下降，步骤分不降 |

## 6. 合成玩具校准（非机器人证据）

为验证「非补偿选择规则可计算」，在本地做了一个 8 层 × 500 候选策略的合成 CMDP。公开分布偏易、隐藏分布偏脆弱/困难；伤害使 episode 归零。结果（`exp/ethics_review_results.json`）：

| 选择器 | 公开分 | 隐藏分 | 隐藏最差层成功率 | 隐藏伤害率 | 攻击性参数 |
|---|---:|---:|---:|---:|---:|
| 平均最优 `avg_public` | 188.99 | 169.52 | 0.738 | 0.0071 | 0.814 |
| 拉格朗日 `λ=10` | 191.39 | 183.38 | 0.883 | 0.0025 | 0.490 |
| 仅盾 `shield_only` | 187.41 | 175.62 | 0.814 | 0.0024 | 0.310 |
| 盾+最差组 `shield_justice` | 189.58 | 181.45 | 0.870 | 0.0019 | 0.276 |

**解读**：
- 平均最优在公开分布上选了最激进的策略（a=0.814），隐藏最差层只有 0.738；盾+最差组把隐藏最差层抬到 0.870、隐藏分 +11.9、伤害率 −73%。
- 调好 λ 的拉格朗日在本玩具中仍是强基线；本方案的差异不是「一定更高分」，而是**约束可审计、可验证、无需猜 λ**。
- 这是合成数据，不能当作真机结论；只说明非补偿选择在算术上可计算、且可能改变最差组。

本地榜单 fixture 的离散度（`exp/leaderboard_dispersion.json`，生成数据）也支持同一诊断：top model 逐任务成功率 21.29–37.32，底部四分位均值 24.93、顶部 34.97；跨模型平均最差任务 Plug In Ethernet 17.73。平均值确实会掩盖 10–15 个点的任务间差异。

## 8. 治理侧建议（可选，不影响参赛主线）

1. **发布 submission 的「伦理卡」**：契约表、数据来源、覆盖矩阵、红队结果、事件日志摘要、已知失效模式。它不是官方要求，但能让评审/复现者判断「这是不是只会刷榜的策略」。
2. **向赛事建议「非补偿安全门」或「负责任 AI 分榜」**：官方排名仍按成功率+步骤分，但增加一个独立的「无严重事件/可复现性」门槛。这样不会把伦理变成可交易分数，也不会让冒险策略在纯排名中系统性占优。
3. **公开失败**：把近失与失败案例脱敏发布，作为社区共同资产；这比只发布成功视频更符合伦理审查的「不良事件报告」精神。

## 9. 本轮最大风险

**一句话**：官方排名只奖励成功率与步骤分，而自设的硬性伦理门在规则不要求、隐藏测试也不惩罚危险行为时只会白白牺牲分数；若不能证明「安全约束在真实分布上同时改善尾部收益」，这套契约就会退化为昂贵的自我束缚。
