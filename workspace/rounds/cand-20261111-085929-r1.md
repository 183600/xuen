# 第 55 轮（承接第 54 轮 v16 GroundEdge-GenSim+++；新一轮灵感循环第 1 轮；本轮灵感：「需求洞察」×「排行榜」）

> 第 54 轮完成了能力侧的动作-鲁棒性双证书（α_S、ρ、J、γ_ce），系统已经能回答"**能不能做、做到多稳**"。本轮把视角翻转：从"系统能做什么"转向"系统**该做什么、做到什么程度、为谁而做**"，并把排行榜作为跨任务、跨竞争者的选择压力。核心矛盾：**H22 需求错位**——真实需求 δ* 是隐变量，显式指令只是其有噪投影，直接优化"说出来的需求"会系统性偏离"真实需求"；**H23 榜单幻觉**——排行榜既提供进化压力又诱发 Goodhart 刷榜，"榜单最优 ≠ 部署最优"；**H24 回声闭环**——需求后验与排行榜互为因果，可能自我强化成"我们只优化我们以为的需求"。

## 0. 直觉与动机

**灵感 1（需求洞察 → 把需求从一句指令变成一条可推断的谱）**
直觉：过去 54 轮几乎都在加固"能力侧"的证据（鲁棒性谱 ρ、动作占用 α_S、联合证书 J）。但用户说"把箱子搬到那边"时，真实需求其实是一个**多维隐向量**：安全（别碰倒杯子）、时延（两分钟内）、能耗（省电）、精度（放正）、可解释（出事能说清）。这些维度用户不会全说，甚至自己也不知道。因此不应把需求当常量，而应建模为**需求谱** `δ*_T ∈ [0,1]^m`，并维护后验 `p(δ*_T | E_T)`，其中证据 `E_T` 包括指令 I、纠正 C、失败反例 F、以及排行榜相对信号 R。核心直觉：**能力证书只有在给定需求下才有意义**——同一份 ρ 在低需求任务上是冗余，在高需求任务上是不足。

**灵感 2（排行榜 → 从"绝对分数"改为"边际需求覆盖/单位成本"）**
直觉：按绝对成功率排榜，会奖励"在简单任务上刷分"的候选，而不是"补上稀缺需求"的能力。更合理的选择压力是 **边际需求覆盖增益除以成本**：`u(S) = Δcover(S;K) / cost(S)`；并且用**置信下界 LCB** 排序而非均值，以对抗小样本评估噪声。这样排行榜不再是"分数军备竞赛"，而是"需求缺口 → 能力补位"的市场：谁更能填补当前需求谱上的缺口，谁排前面。只有当两个候选的置信区间不重叠时才允许给出严格次序，否则只输出**偏序/并列**。

**灵感 3（排行榜也要带证书 → 反 Goodhart 的第一性约束）**
直觉：任何被优化的榜单都会被刷：评估集污染、代理指标偷换、评估分布与部署分布漂移，都会让"榜首"偏离"部署最优"。所以排行榜本身必须是**可裁决对象**，携带**排行榜鲁棒性证书** `L = (RI, Div, ε_shift, Probe, ρ_game)`：排序区间 RI、评估-部署分布多样性 Div、漂移上界 ε_shift、未公开需求探针 Probe、以及代理-真值相关性 ρ_game。只有当 RI 不重叠、Div 足够、ρ_game 未崩塌时，排序才"可裁决"；否则系统只应相信偏序，不应把"第一名"当部署依据。

**灵感 4（需求洞察 ↔ 排行榜闭环 → 选择压力反过来校准需求后验）**
直觉：单机观察到的需求证据是稀疏的；排行榜提供跨竞争者/跨任务的**相对信号**——别人在某需求维度上得分高，可能说明该维度更重要或更可达。但这是有偏信号（幸存者偏差、评估偏差），所以只能作为**弱先验**注入：用贝叶斯因子**限幅**（clipping）并入后验，绝不能覆盖本地证据。于是形成闭环：`本地需求证据 → 需求后验 → 需求加权排行榜 → 跨任务弱信号回注 → 后验校准 → 重新排序`。这与第 54 轮的"云规划-边校验-反向解释-重剖分"闭环同构，但把"动作空间"换成"需求空间"。

**灵感 5（与既有证书体系融合 → 需求条件化部署证书）**
直觉：把第 54 轮的联合证书 J 升级为 **需求条件化证书** `J_δ = (J, Δ_θ, Cov, Gap, L)`：`Cov` 是需求后验可信集上的覆盖概率，`Gap` 是未被覆盖的需求维度集合。部署判据从"`ρ ≥ ρ_min` 的绝对阈值"改为"**在需求可信集上覆盖概率 ≥ θ_dep 且关键缺口为空**"。这把体系从"能力自证"推进到"需求-能力匹配证"，也解释了为什么同一技能在不同客户/任务上"可用性"不同。

## 1. 形式化定义（增量：定义 121–126）

**定义 121（需求谱与需求后验）**
需求维度 `D = {d_1,...,d_m}`（安全、时延、能耗、覆盖、精度、成本…）。任务/上下文 T 的隐需求 `δ*_T ∈ [0,1]^m`。证据 `E_T = (I, C, F, R)`：指令、用户纠正、失败反例、排行榜相对信号。需求后验 `p(δ*_T | E_T)`，**可信需求集** `Δ_θ = HPD_θ(p) = {δ : p(δ|E_T) ≥ θ}`（最高密度区域），并记后验校准误差 `cal = |P(δ* ∈ Δ_θ) - (1-α)|`。

**定义 122（需求-能力覆盖）**
能力证书（承接第 53/54 轮）`K = (ρ, α_S, J, γ_ce)`，维度可达水平 `cap_d(K) ∈ [0,1]`。单点覆盖
```
cover(δ, K) = ∏_{d∈D} σ((cap_d(K) - δ_d) / τ_d)
```
其中 σ 为 sigmoid、τ_d 为维度容差。需求后验下的**覆盖概率**
```
Cov(K) = ∫_{δ∈Δ_θ} cover(δ, K) · p(δ | E_T) dδ
```

**定义 123（需求缺口与边际增益）**
缺口集 `Gap(K) = { d∈D : P_{δ~p}(cap_d(K) < δ_d) > 1-θ }`。技能 S 的**边际需求增益** `Δcover(S;K) = Cov(K⊕S) - Cov(K)`，**单位成本增益** `u(S;K) = Δcover(S;K) / cost(S)`。关键缺口 `Gap_crit(K) = Gap(K) ∩ D_crit`。

**定义 124（需求加权排行榜）**
对候选 `{S_j}`，用自助法（bootstrap）或贝叶斯后验得到 `u` 的下分位数 `LCB_α`。排序定义为
```
Rank(S_i) ≺ Rank(S_j)  ⇔  LCB_α(u(S_i)) > LCB_α(u(S_j))
```
若两候选的 `LCB` 区间重叠，则记为 `S_i ~ S_j`（不可分），排行榜输出**偏序**而非强行全序。

**定义 125（排行榜鲁棒性证书）**
```
L = (RI, Div, ε_shift, Probe, ρ_game)
```
- `RI`：每个名次的 bootstrap 排名区间；
- `Div`：评估任务分布与部署需求分布的覆盖度（1 − 归一化 MMD）；
- `ε_shift`：分布漂移上界 `W_1(P_eval, P_deploy) ≤ ε_shift`；
- `Probe`：未公开、定期轮换的需求探针集合；
- `ρ_game`：代理指标与探针真值的秩相关。
**可裁决（decidable）** 当且仅当：`RI` 首位不重叠 ∧ `Div ≥ θ_div` ∧ `ρ_game ≥ θ_game`。否则榜单只具备"建议"地位。

**定义 126（需求条件化部署证书）**
```
J_δ = (J, Δ_θ, Cov, Gap, L)
```
部署可行当且仅当
```
Cov(K) ≥ θ_dep  ∧  Gap_crit(K) = ∅  ∧  L.decidable
```
即：能力必须在**需求可信集**上以足够概率覆盖需求、无关键缺口、且所依据的排行榜本身可裁决。

## 2. 关键算法 伪代码

### IP-121 DIP（Demand Insight Profiling）

```python
def demand_posterior(evidence, D, prior, sim):
    feats = featurize(evidence, D)            # I, C, F, R -> 需求维度特征
    post = amortized_variational_infer(prior, likelihood(feats), sim)
    delta_cred = hpd_region(post, mass=0.90)  # 可信需求集
    return post, delta_cred

def probe_coverage(delta_cred, deploy_dist, n=512):
    return 1 - normalized_mmd(sample(delta_cred, n), sample(deploy_dist, n))
```

### IP-122 DCL（Demand-weighted Capability Leaderboard）

```python
def marginal_demand_gain(skill, K, post, n=1024):
    deltas = sample(post, n)
    gains = [cover(d, compose(K, skill)) - cover(d, K) for d in deltas]
    return mean(gains)

def demand_weighted_utility(skill, K, post, cost, alpha=0.1):
    gains = bootstrap_dist(lambda: marginal_demand_gain(skill, K, post), B=1000)
    return quantile([g / cost for g in gains], alpha)   # LCB_alpha(u)

def build_leaderboard(cands, K, post, cost):
    scores = {s: demand_weighted_utility(s, K, post, cost[s]) for s in cands}
    ri = bootstrap_rank_interval(scores, B=1000)
    return partial_rank_by_lcb(scores, ri)   # 区间重叠 -> tie
```

### IP-123 LRC（Leaderboard Robustness Certificate）

```python
def leaderboard_certificate(board, eval_dist, deploy_dist, probes, gaming_log):
    ri      = board.rank_interval
    div     = probe_coverage(board.cred_region, deploy_dist)
    eps     = wasserstein1(eval_dist, deploy_dist)
    rho_gam = spearman(board.proxy_scores, probe_scores(probes))
    decidable = (ri[0].hi < ri[1].lo) and (div >= THETA_DIV) and (rho_gam >= THETA_GAME)
    return LeaderboardCert(ri, div, eps, rho_gam, decidable)
```

### IP-124 DCA（Demand-Capability Alignment）

```python
def demand_capability_align(K, post, cred, theta_dep):
    cov = integrate(lambda d: cover(d, K), post, over=cred)
    gap = [d for d in D
           if posterior_prob(K.cap[d] < d_value, post) > (1 - THETA)]
    feasible = (cov >= theta_dep) and not critical_gap(gap, D_crit)
    return AlignResult(cov, gap, feasible)
```

### IP-125 GDR（Goodhart / Gaming Detection & Rotation）

```python
def gaming_guard(board, probe_bank, tau_game=0.15):
    rho_true = spearman(board.proxy_scores, probe_scores(probe_bank))
    drift    = abs(rho_true - board.expected_rho)
    if drift > tau_game:                       # 代理-真值背离 -> 判定刷榜
        return ('alarm', rotate_probes(probe_bank), 'freeze_ranking')
    return ('ok', rho_true)
```

### IP-126 DCC（Demand-Conditioned Certificate）

```python
def demand_conditioned_cert(seq, gamma_ce, post, cred, L, theta_dep):
    J = joint_certificate(seq, gamma_ce, delta_a_budget, rho_min)   # 第 54 轮
    if J is None:
        return ('reject', 'capability_cert_failed')
    cov, gap, ok = demand_capability_align(J, post, cred, theta_dep)
    if not L.decidable:
        return ('defer', 'leaderboard_not_decidable', L)
    if not ok:
        return ('reject', 'demand_gap', gap)
    return ('ok', DemandCert(J, cred, cov, gap, L))
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| DIP | O(|E|·|D| + N_post) | O(|D| + N_post) | 后验校准、可信集覆盖 |
| DCL | O(\|C\|·N·B) | O(\|C\|) | LCB 排序、bootstrap 一致性 |
| LRC | O(N·(\|C\|+\|Probe\|)) | O(\|C\|+\|Probe\|) | 探针独立、漂移有界 |
| DCA | O(\|D\|·N_post) | O(\|D\|) | cap 单调、缺口判定 sound |
| GDR | O(\|Probe\|·log\|Probe\|) | O(\|Probe\|) | 探针轮换、相关性检出力 |
| DCC | O(DCA + 第 54 轮 J) | O(\|D\|+\|A\|) | 三条件合取 sound |

**正确性定理（Demand-Conditioned Ranking Soundness, DCRS）**
假设第 54 轮 (A26)–(A28) 成立；并新增：
**(A29)** 需求后验校准：`P(δ* ∈ Δ_θ) ≥ 1-α`；
**(A30)** `W_1(P_eval, P_deploy) ≤ ε`，且 `cover(·,K)` 对 δ 是 L_c-Lipschitz；
**(A31)** 探针与部署需求可交换且未泄漏；
**(A32)** 效用估计器满足浓度 `|û - u| ≤ γ`（概率 ≥ 1-β）。
则对排行榜首位候选 `Ŝ` 与真实最优 `S*`：
```
E[cover(δ*, K⊕Ŝ)] ≥ cover(δ*, K⊕S*) - 2γ - L_c·ε - α      （概率 ≥ 1-β-α）
```
部署失败概率上界：
```
P_fail ≤ (1 - θ_dep) + α + L_c·ε + P(gaming) + P(L 不可裁决)
```
关键：**需求覆盖而非绝对能力**决定部署；**偏序而非全序**决定选择；**探针独立**决定榜单可裁决。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 需求维度遗漏/规格错误（盲区） | 高 | 开放式需求发现 + 残差探针 + 红队注入 |
| 排行榜刷榜/评估集泄漏 | 高 | 未公开探针 + 定期轮换 + 证书化偏序 |

## 6. 本轮最大风险

**一句话**：需求洞察与排行榜会形成自我强化的回路——一旦排行榜的代理指标被默认等同于"需求"，而探针泄漏或需求维度被漏设，系统就会以极高置信度去优化一个"幻觉需求"；因此必须始终把排行榜当作**带证书的证据而非真值**，坚持探针留出与轮换、需求维度开放发现、以及"只信偏序不信榜首"三重护栏，宁可承认需求不可知，也不能把榜单第一误当作部署依据。

def calibrate_post(post, holdout):
    # 用留出数据验证可信集覆盖率，偏差超过阈值则回退到更宽的可信集
    emp = empirical_coverage(post, holdout)
    if abs(emp - 0.90) > 0.05:
        post = widen(post, target=0.90)
    return post

    return partial_rank_by_lcb(scores, ri)             # 区间重叠 -> tie
```

### IP-125 GDR

def gaming_guard(board, probe_bank, tau_game=0.15):
    rho_true = spearman(board.proxy_scores, probe_scores(probe_bank))
    drift    = abs(rho_true - board.expected_rho)
    if drift > tau_game:
        return ('alarm', rotate_probes(probe_bank), 'freeze_ranking')
    return ('ok', rho_true)
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| DIP | O(\|E\|·\|D\| + N_post) | O(\|D\|+N_post) | 后验校准、可信集覆盖率 ≥ 1-α |
| DCL | O(\|C\|·N·B) | O(\|C\|) | LCB 排序一致、bootstrap 收敛 |
| LRC | O(N·(\|C\|+\|Probe\|)) | O(\|C\|+\|Probe\|) | 探针独立、漂移有界、可裁决 sound |
| DCA | O(\|D\|·N_post) | O(\|D\|) | cap 单调、缺口判定 sound |
| GDR | O(\|Probe\|·log\|Probe\|) | O(\|Probe\|) | 秩相关检出力、轮换无泄漏 |
| DCC | O(DCA + J) | O(\|D\|+\|A\|) | 三条件合取 sound、需求条件闭合 |

**正确性定理（Demand-Conditioned Ranking Soundness, DCRS）**
假设第 54 轮 (A26)–(A28) 成立，并新增：
**(A29)** 需求后验校准：`P(δ* ∈ Δ_θ) ≥ 1-α`；
**(A30)** `W_1(P_eval,P_deploy) ≤ ε` 且 `cover(·,K)` 对 δ 为 L_c-Lipschitz；
**(A31)** 探针与部署需求可交换、未泄漏；
**(A32)** 效用估计器浓度 `|û-u| ≤ γ`（概率 ≥ 1-β）。
则排行榜首位 `Ŝ` 相对真实最优 `S*`：
```
E[cover(δ*, K⊕Ŝ)] ≥ cover(δ*, K⊕S*) - 2γ - L_c·ε - α      （概率 ≥ 1-β-α）
```
部署失败概率：
```
P_fail ≤ (1-θ_dep) + α + L_c·ε + P(gaming) + P(L 不可裁决)
```
关键：**以需求覆盖而非绝对能力判定部署；以偏序而非全序选择候选；以探针独立保证榜单可裁决。**

## 5. 本轮最大风险

**一句话**：需求洞察与排行榜构成自我强化回路——一旦排行榜代理指标被默认等同于"需求"，而探针泄漏或需求维度漏设，系统会以极高置信度优化一个"幻觉需求"；故必须把排行榜当作**带证书的证据而非真值**，坚持探针留出与轮换、需求维度开放发现、以及"只信偏序不信榜首"三重护栏，宁可承认需求不可知，也绝不把榜单第一误当作部署依据。
