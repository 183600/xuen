# 第 1 轮（本灵感循环第 1 轮；承接第 4 轮 InstructGauge-WR 基线；本轮灵感：「需求洞察」×「强化学习训练」）

> **基线**：第 4 轮 InstructGauge-WR（IP-328–333；定义 448–467；引理 59–62；实验 E457–E472）。InstructGauge v3 / ToolGauge / LeanGauge / MODGAUGE 的退化链继续继承不变。
> 本轮纪律：**增量升级 + 严格退化 + 需求可证**。需求洞察只把「软偏好与验收阈值」显式化，RL 训练只在可采纳策略类内做优化；任一环节不可用都必须退回 InstructGauge-WR，需求与训练是增强项、不是依赖项。

## 0. 直觉与动机

**灵感 1（需求洞察 → 可审计的「需求剖面」，而不是一句自然语言或一个标量奖励）**
直觉：盲区修复里，用户说「把那个反光的修好」时，真正的需求至少有三层：硬约束（不能划伤、不能超行程、不能跨不可逆动作）、软偏好（先快后好还是先好后快）、验收阈值（什么算修好、什么算可接受）。硬约束不能从偏好数据里「学」出来，只能来自预注册的安全本体；软偏好与阈值才是需求洞察的对象。更关键的是，需求不是静态文本，而是通过接受/拒绝、纠正、返工、停留时间等弱信号**逐轮显示**出来的。因此正确的接口不是「NL→奖励」，而是「交互证据→带歧义集与来源的需求剖面 ν」；ν 只改目标排序与阈值，**绝不扩大能力与安全可行域**。

**灵感 2（强化学习训练 → 可采纳策略类内的优化器，而不是真理来源）**
直觉：RL 擅长长程信用分配、工具选择、视角选择与「何时问人」，这些正是盲区修复的难点。但 RL 只会优化你给它的奖励；需求错、奖励就错，策略会把错误需求执行得越来越熟练。正确的用法不是「训练一个端到端策略替代证书」，而是**在带屏蔽的约束 MDP 内训练一个可替换的策略增强项**：硬约束由 shield 保证，软目标由需求剖面编译，训练分布用域随机化与课程覆盖，部署前必须通过策略证书（OPE 下界 + 安全上界）。RL 是优化器，证书是门卫；门卫不通过就退回基线策略。

**灵感 3（两者耦合 → 需求-策略-证据的双向回路，必须用「证书门控 + 主动询问」切断自我确认）**
直觉：需求决定奖励，策略决定动作，动作又产生新的证据去更新需求——这是一个以「用户真实需求」为隐变量的 POMDP。危险在于自我确认：策略按错误需求行动，产生的证据又恰好被同一错误需求解释，最终「内部一致但整体错误」。解法不是禁用 RL，而是四根结构支柱：**硬软分离**（硬约束只来自安全本体）、**歧义鲁棒优化**（对需求歧义集做最坏情况优化，而不是对点估计优化）、**策略证书门控**（OPE 下界与安全上界同时通过才部署）、**主动询问与信念条件分块**（歧义高时缩短 K 或发问，用信息价值换安全）。

## 1. 研究问题（本轮要回答什么）

- **Q1（需求可证性）**：能否把需求洞察写成带硬/软分离、来源与歧义集的需求剖面，使其可校准、可审计，并且不会通过奖励扩大能力？
- **Q2（训练可部署性）**：约束 RL 训练出的策略，在什么条件下可以被证明「不差于基线且不增加安全违背」？策略证书需要哪些假设？
- **Q3（耦合可控性）**：需求歧义与策略分布偏移互相放大时，能否用歧义鲁棒目标、主动询问、信念条件分块与退化链把损失压回可界，并在失效时严格退回基线？

## 2. 三条设计原则（正式化见产物区定义 468–483）

**P1 需求可分离性（Need Separability）**
需求剖面 `ν = (H, O, τ, prov)`：`H` 为安全本体中的硬约束，永不由偏好数据估计；`O` 为软目标及权重，`τ` 为验收阈值，二者由交互证据估计。奖励编译器 `R_ν` 必须满足 `argmax R_ν ⊆ A_adm(s)`，且 `scope(R_ν) ⊆ T₀ × A_adm`。需求洞察只能改偏好与阈值，不能改工具集、物理包线或不可逆屏障。

**P2 歧义鲁棒训练（Ambiguity-Robust Training）**
需求后验不产生点估计，而给出校准歧义集 `N_t`。训练目标不是 `max_π J_{ν̂}(π)`，而是 `max_π inf_{ν∈N_t} J_ν(π) − λ C_safe(π)`，并加行为正则 `D(π, π_ref) ≤ ε_trust` 保持可退化。只有 `N_t` 覆盖真实需求时，鲁棒下界才有意义；覆盖失效则退回基线目标。

**P3 证书门控与主动询问（Certificate Gate & Active Query）**
需求证书与策略证书都是开关而非装饰：需求证书不唯一/漂移 → `ν=ν_⊥` 稳健需求 + 缩短 K + 询问；策略证书不通过 → 部署基线策略。主动询问只在 `VOI(q) > cost(q)` 时触发，且询问动作永不跨不可逆屏障。

## 3. 与基线的接口（如何退化）

- 需求证书失效 / 歧义集不唯一 / 需求漂移 ⇒ `ν=ν_⊥`，`R_ν=R₀`，K 回基线，等价 InstructGauge-WR；
- 需求剖面只有硬约束、无可用软偏好 ⇒ 退回基线字典序目标，不训练新策略；
- 策略证书不通过 / OPE 置信区间与基线重叠 / 安全上界超预算 ⇒ 冻结 RL 策略，部署基线策略；
- 策略在不可逆动作附近越界 ⇒ 强制 K=1 + 独立回执交叉验证；
- 所有新组件失效 ⇒ InstructGauge-WR v4 ⇒ InstructGauge v3 ⇒ ToolGauge ⇒ LeanGauge / MODGAUGE 原样。

## 4. 预期贡献

1. 一个硬/软分离、带来源与歧义集的**需求剖面 + 需求证书**，把「用户到底要什么」从自然语言假设变成可校准对象；
2. 一个**歧义鲁棒约束 RL 训练器**，在 shield 与行为正则下优化需求条件策略，并给出悲观下界；
3. 一个**策略证书门控**，用 OPE 下界与安全上界决定是否部署，保证「不优于基线就不部署」；
4. 一个**信念条件分块 + 主动询问**接口，把需求歧义转成可支付的询问/缩短块长，而非沿时间轴放大；
5. 一条可证伪路径：E473–E488 覆盖需求校准、奖励可采纳、鲁棒训练、策略证书、主动询问、需求漂移、sim-to-real 与 50Hz 时序。

## 5. 本轮最大风险

**一句话**：需求剖面和 RL 策略会互相「确认」——错误但自洽的软需求被优化成高回报行为，而策略证书只在训练分布内有效；最大风险是 OOD 需求变化下的「证书正确、需求错误」。

## 2. 形式化定义（要点）

**定义 468（需求剖面 Need Profile）**
需求剖面是一个四元组
```
ν = (H, O, τ, prov)
H = {h_k}_{k=1..K_H}         # 安全本体硬约束，版本化、只读
O = {(o_j, w_j)}_{j=1..K_O}  # 软目标与权重，w_j ≥ 0
τ = {τ_m}_{m=1..K_τ}         # 验收阈值
prov = {(o_j, evidence_id, timestamp)}  # 每个软目标/阈值的来源
```
`ν` 诱导字典序偏好 `≻_ν`：硬约束绝对优先，软目标其次，成本最后。`ν` 不改变动作集 `A`、工具集 `T₀` 或 `A_adm`。

**定义 469（交互证据与需求后验）**
交互证据流 `e_t = (ℓ_t, a_{t-1}, y_t, f_t, r_t, d_t)`，其中 `f_t` 是接受/拒绝/纠正反馈，`r_t` 是返工标记，`d_t` 是停留时间。需求后验
```
b_t(ν) ∝ P(ν) · Π_{i=1}^{t} P(e_i | ν)
```
软目标权重用 Bradley–Terry / 偏好似然更新，阈值用带删失的生存模型更新；硬约束 `H` 不参与后验更新。

**定义 470（需求歧义集 Need Ambiguity Set）**
给定置信水平 `1−α` 与共形校准集 `D_need`，定义
```
N_t = { ν ∈ N : b_t(ν) ≥ β_t } ∩ C_α(e_{1:t})
```
其中 `C_α` 是需求剖面的共形预测集，满足在可交换性下 `P(ν* ∈ C_α) ≥ 1−α`。`β_t` 是可调的尾部截断，用于把极低后验的质量排除在训练目标之外。

**定义 471（需求证书 Need Certificate）**
```
NeedCert_t = (b_t, N_t, H, prov, coverage_t, shift_t, valid_t)
valid_t = (coverage_t ≥ 1−α) ∧ (|N_t| ≤ N_max) ∧ (shift_t ≤ ε_need)
```
`coverage_t` 由校准集的经验覆盖估计，`shift_t` 是当前证据分布相对校准分布的漂移分。`valid_t=false` 时不得用 `ν̂` 条件化执行。

**定义 472（需求-奖励编译 Need Reward Compilation）**
```
R_ν(s,a) = ( r_H(s,a), r_O^ν(s,a), r_cost(s,a) ; ≻_lex )
r_H(s,a) = −∞   若 a ∉ A_adm(s)，否则 0
r_O^ν(s,a) = Σ_j w_j · o_j(s,a)
r_cost(s,a) = Δt(s,a) + λ_e · ΔE(s,a)
```
字典序为 `r_H ≻ r_O ≻ r_cost`。若 `NeedCert` 无效，编译器输出基线奖励 `R₀`，并令 `ν=ν_⊥`。

**定义 473（需求条件 CMDP）**
```
M_ν = (S, A, P, R_ν, C, γ, b_0, d)
```
`C = (C_1,…,C_m)` 是安全代价向量（碰撞、越界、不可逆误用、超温等），`d` 是预算。硬约束 `H` 通过 shield 进入 `A_adm`，而不是通过罚项进入 `C`；`C` 只承载可量化的软安全余量。

**定义 474（可采纳策略类 Admissible Policy Class）**
```
Π_adm = { π : ∀s, supp π(·|s) ⊆ A_adm(s) ∧ C_safe(π) ≤ d }
```
`A_adm` 继承第 4 轮 `KinematicAdmissibleSet`、CVC 与前缀封闭分块约束；RL 训练不得扩张 `Π_adm`。

**定义 475（歧义鲁棒目标 Ambiguity-Robust Objective）**
```
J_rob(π; N_t) = inf_{ν ∈ N_t} J_ν(π) − λ · C_safe(π)
```
`λ ≥ 0` 是拉格朗日乘子。若 `N_t` 退化为单点，`J_rob` 退化为标准约束 RL 目标；若 `N_t=N`（完全不可辨识），`J_rob` 退化为最坏情况稳健目标，并触发 K=1/基线策略。

**定义 476（行为正则训练目标）**
```
max_π  J_rob(π; N_t)
s.t.   E_s[D_KL(π(·|s) || π_ref(·|s))] ≤ ε_trust
       C_safe(π) ≤ d
```
第一项保证策略不会偏离基线太远，第二项保证安全预算。训练使用拉格朗日对偶：
```
L(π,λ,μ) = J_rob(π;N_t) − λ(C_safe(π)−d) − μ(D_KL(π||π_ref)−ε_trust)
```

**定义 477（主动询问的信息价值 VOI）**
```
VOI(q | b_t) = E_{o∼P(·|b_t,q)}[ max_a E_{ν∼b_t(·|o)} R_ν(s,a) ]
            − max_a E_{ν∼b_t} R_ν(s,a)
            − η · cost(q)
```
仅当 `VOI(q|b_t) > 0` 且询问动作在安全集内时发问。询问不改变物理状态，只改变需求后验；因此不跨不可逆屏障。

**定义 478（信念条件块长）**
```
K_t = clip( floor( ε_drift / (L_R · (H(b_t) + ε_need) + L_C · σ_C) ), 1, K_max )
```
`L_R`、`L_C` 是奖励/安全代价对需求参数的 Lipschitz 常数，`σ_C` 是安全余量估计标准差。`H(b_t)` 越大、`σ_C` 越大，`K_t` 越小；`K_t=1` 时退化为逐步执行。

**定义 479（策略证书 Policy Certificate）**
```
PolicyCert(π) = (J_lcb(π), C_ucb(π), OOD(π), valid(π))
```
`J_lcb` 由离线/在线 OPE（FQE / 双重稳健）加 bootstrap 或共形下界得到，`C_ucb` 是安全代价的上置信界，`OOD` 是策略访问分布相对训练分布的漂移分。三者必须由独立校准集给出。

**定义 480（部署门 Deployment Gate）**
```
deploy(π) ⇔ J_lcb(π) ≥ J_ref + δ ∧ C_ucb(π) ≤ d ∧ OOD(π) ≤ ε_ood
```
门是**单向下行**的：一旦 `deploy=false`，本块必须使用 `π_ref`；不允许在同一块内重新打开 RL 策略。`J_ref` 是 `π_ref` 的证书下界。

**定义 481（需求漂移监控 e-process）**
对需求摘要统计量 `z_t`（软权重、阈值或后验矩），在零假设“需求未变”下构造
```
E_t = Π_{i=1}^{t} (1 + λ_i (z_i − μ_0)),   λ_i ∈ [−1,1]
```
当 `E_t ≥ 1/α` 时告警。由 Ville 不等式，零假设下 `P(sup_t E_t ≥ 1/α) ≤ α`。告警后冻结 `π_θ`、重置 `NeedCert`、令 `K=1` 直到重新校准。

**定义 482（NR-7C 闭环接口）**
```
NR-7C = Need → Ground → Hyp → Reward → Plan → Train/Execute → Certify → Bind
```
`Need` 输出 `NeedCert`；`Ground` 继承 NLI-Box；`Reward` 输出 `R_ν` 与 shield；`Plan` 只在 `A_adm` 内搜索并继承不可逆屏障；`Train/Execute` 使用通过 `PolicyCert` 的策略或 `π_ref`；`Certify` 在块边界复核需求、策略与 `SpatialCert`；`Bind` 继承 CVC 回执绑定。

**定义 483（严格退化等价）**
依次关闭需求剖面、需求奖励、鲁棒训练、策略证书、主动询问与需求监控，`NeedGauge-RL` 分别退化为：基线字典序目标、无需求条件奖励、标准约束 RL、`π_ref`、无询问策略、无漂移监控的 v4 闭环；全部关闭后与 InstructGauge-WR 的 `WRC-ROS-7C` 逐动作等价。

class NeedProfiler:
    def __init__(self, need_space, safety_ontology, conformal,
                 alpha=0.10, beta=0.01, n_max=8, eps_need=0.10):
        self.space = need_space
        self.ontology = safety_ontology
        self.conformal = conformal
        self.alpha = alpha
        self.beta = beta
        self.n_max = n_max
        self.eps_need = eps_need
        self.history = []
        self.b = self.space.prior()

    def update(self, evidence):
        self.history.append(evidence)
        self.b = self.space.posterior(self.history, self.b)
        ambiguity = self.conformal.set(self.history, self.b, self.alpha)
        ambiguity = {nu for nu in ambiguity if self.b.get(nu, 0.0) >= self.beta}
        shift = self.conformal.drift(self.history)
        valid = (self.conformal.coverage() >= 1 - self.alpha
                 and len(ambiguity) <= self.n_max
                 and shift <= self.eps_need)
        return NeedCert(posterior=self.b, ambiguity=ambiguity,
                        hard=self.ontology.hard_constraints,
                        provenance=self.space.provenance(self.history),
                        coverage=self.conformal.coverage(),
                        shift=shift, valid=valid)


class NeedRewardCompiler:
    def __init__(self, ontology, kloop, cvc):
        self.ontology = ontology
        self.kloop = kloop
        self.cvc = cvc

    def admissible(self, s, actions):
        return [a for a in actions
                if self.kloop.is_kinematically_valid(a, s)
                and self.cvc.feasible(a, s)]

    def compile(self, cert):
        if not cert.valid:
            return BaselineLexicographicReward(self.ontology)
        return LexicographicReward(hard=cert.hard,
                                   soft=cert.point.soft,
                                   thresholds=cert.point.thresholds)

    def robust_score(self, cert, s, a):
        return min(self.compile(nu).score(s, a)
                   for nu in cert.ambiguity)


class ConstrainedRLTrainer:
    def __init__(self, env, shield, pi_ref, gamma=0.99,
                 trust=0.10, target_cost=None):
        self.env = env
        self.shield = shield
        self.pi_ref = pi_ref
        self.gamma = gamma
        self.trust = trust
        self.target_cost = target_cost

    def train(self, compiler, need_sampler, epochs=200, batch=4096):
        pi = self.pi_ref.clone()
        lam = 0.0
        mu = 0.0
        for epoch in range(epochs):
            for scene in self.env.curriculum(epoch):
                need_cert = need_sampler.sample(scene, epsilon=0.1)
                if not need_cert.valid:
                    continue
                reward = compiler.compile(need_cert)
                rollouts = self.env.rollout(
                    pi, reward, shield=self.shield, need=need_cert)
                pi = self.ppo_update(pi, rollouts, lam, mu, self.trust)
                lam = max(0.0, lam + self.eta_lambda
                          * (rollouts.cost_mean - self.target_cost))
                mu = max(0.0, mu + self.eta_mu
                         * (rollouts.kl_mean - self.trust))
        return pi


class PolicyCertifier:
    def __init__(self, ope, safety, ood, alpha=0.05, delta=0.02,
                 eps_ood=0.10):
        self.ope = ope
        self.safety = safety
        self.ood = ood
        self.alpha = alpha
        self.delta = delta
        self.eps_ood = eps_ood

    def certify(self, pi, pi_ref, env):
        j_lcb = self.ope.lower_bound(pi, env, self.alpha / 2)
        j_ref = self.ope.lower_bound(pi_ref, env, self.alpha / 2)
        c_ucb = self.safety.upper_bound(pi, env, self.alpha / 2)
        ood = self.ood.score(pi, env)
        valid = (j_lcb >= j_ref + self.delta
                 and c_ucb <= self.safety.budget
                 and ood <= self.eps_ood)
        return PolicyCert(j_lcb, c_ucb, ood, valid)


class NeedAwareController:
    def __init__(self, belief, k_max=8, eta=0.02,
                 lipschitz=1.0, eps_need=0.05):
        self.belief = belief
        self.k_max = k_max
        self.eta = eta
        self.lipschitz = lipschitz
        self.eps_need = eps_need

    def value_of_information(self, b, query):
        post = self.belief.after(b, query)
        return (self.expected_value(post)
                - self.expected_value(b)
                - self.eta * query.cost)

    def best_query(self, cert):
        return max(cert.queries, key=lambda q: self.value_of_information(
            cert.posterior, q), default=None)

    def should_query(self, cert):
        q = self.best_query(cert)
        return q is not None and self.value_of_information(
            cert.posterior, q) > 0.0

    def chunk_length(self, cert, drift_bound, sigma_cost):
        entropy = entropy_of(cert.posterior)
        denom = self.lipschitz * (entropy + self.eps_need) + sigma_cost
        return max(1, min(self.k_max, int(drift_bound / denom)))


class NeedChangeMonitor:
    def __init__(self, alpha=0.05):
        self.alpha = alpha
        self.e_value = 1.0
        self.alarm = False

    def update(self, z_t, mu_0, lam_t):
        self.e_value *= max(1e-12, 1.0 + lam_t * (z_t - mu_0))
        self.alarm = self.e_value >= 1.0 / self.alpha
        return self.alarm

    def reset(self):
        self.e_value = 1.0
        self.alarm = False


def needgauge_rl(M, s, ell=None):
    evidence = M.sensor.evidence(s, ell)
    need_cert = M.need.update(evidence)

    if not need_cert.valid:
        return instructgauge_wr(M, s, ell,
                                reward=M.reward_compiler.baseline())

    if M.ctrl.should_query(need_cert):
        q = M.ctrl.best_query(need_cert)
        reply = M.hri.query(q)
        need_cert = M.need.update(reply)
        if not need_cert.valid:
            return instructgauge_wr(M, s, ell,
                                    reward=M.reward_compiler.baseline())

    reward = M.reward_compiler.compile(need_cert)
    iota = M.nlib.ground(ell, M.scene, M.ontology)
    H = M.lbox.hypothesize(s, M.dbox.R[s], iota)

    if M.policy_cert.valid and M.policy_cert.need_id == need_cert.id:
        policy = M.rl.policy
    else:
        policy = M.baseline_policy

    K = M.ctrl.chunk_length(need_cert, M.drift_bound(s),
                            M.safety.sigma_cost(s))
    C = M.iac.plan_chunk(iota, H, M.tools, K, M.drift_bound(s),
                         policy=policy, reward=reward)
    C = M.iac.enforce_irreversible_barrier(C)

    C, spatial_cert, claims = M.wrc.execute(M, s, iota, C)

    M.monitor.update(need_cert.summary, M.need.baseline_mean,
                     M.need.e_lambda(need_cert))
    if M.monitor.alarm:
        M.rl.freeze()
        M.need.reset_after_drift()
        M.policy_cert.invalidate()

    return C, need_cert, spatial_cert, claims


def NeedGauge_RL_round(M, obs, audio, tac, depth, det, ell=None):
    for s in M.dbox.detect_blind_spot():
        if s not in M.inflight:
            M.inflight.add(s)
            spawn_async(needgauge_rl, M, s, ell)
    return MODGAUGE_round(M, obs, audio, tac, depth, det)

## 4. 推导

**引理 63（需求-奖励可采纳性）**
若 `NeedCert` 有效且 `R_ν` 按定义 472 编译，则任何对 `R_ν` 贪心的策略都满足 `supp π(·|s) ⊆ A_adm(s)`；需求后验、软权重与阈值的变化不会扩张 `A`、`T₀` 或 `A_adm`。证明：硬约束 `H` 只读安全本体且通过 `r_H=−∞` 把非可采纳动作排除；软目标项只在 `A_adm` 内重排；`scope(R_ν)` 不引用新工具或新物理量；因此奖励只改偏好，不改能力。

**引理 64（歧义鲁棒下界）**
若真实需求 `ν* ∈ N_t` 以概率至少 `1−α` 成立，且奖励有界，则
```
J_rob(π;N_t) ≤ J_{ν*}(π)
```
以概率至少 `1−α` 成立。因此最大化 `J_rob` 得到的策略对真实需求提供悲观下界。证明：`inf_{ν∈N_t}` 不超过集合内任一元素，取 `ν*` 即得；覆盖事件概率由定义 470 保证。

**引理 65（策略证书门控的有效性）**
若 `J_lcb` 与 `C_ucb` 分别在 `1−α/2` 置信水平下有效，且 `OOD` 检验有效，则 `deploy(π)=true` 蕴含真实回报至少 `J_ref+δ` 且真实安全代价不超过 `d`，总失败概率不超过 `α`。证明：对回报下界、安全上界与 OOD 三个事件做联合界；部署门要求三者同时成立。

**引理 66（信念条件块长的陈旧界）**
在定义 478 的块长规则下，单块的需求条件遗憾满足
```
Regret_chunk(C_t) ≤ K_t · L_R · (H(b_t) + ε_need) + K_t · L_C · σ_C
```
且 `K_t` 随 `H(b_t)`、`σ_C` 单调不增；当需求完全不可辨识时 `K_t=1`，遗憾退化为单步遗憾。证明：块内需求参数不变，奖励与安全代价对需求的 Lipschitz 性给出逐步误差上界；对 K_t 步求和并代入定义 478 的分母即得；单调性由表达式直接可得。

**引理 67（主动询问的无害性与收益）**
询问动作不改变物理状态，只在 `VOI(q)>0` 时发问，因此不会引入新的安全违背；若询问预算未耗尽，期望决策收益至少增加 `VOI(q)`，否则退回保守块长或基线策略。证明：询问动作属于只读信息动作，不进入 `A_adm` 的物理执行分支；VOI 定义 477 正是询问前后最优期望回报之差减去询问成本，正值保证期望改进。

**引理 68（需求漂移告警的假阳性控制）**
在零假设“需求分布未变”下，定义 481 的 e-process 满足
```
P( sup_t E_t ≥ 1/α ) ≤ α
```
告警后的检测延迟由 `log(1/α) / KL(P_1 || P_0)` 上界控制。证明：Ville 不等式直接给出假阳性界；检测延迟由 e-process 的对数增长率与 KL 散度关系得到。

**引理 69（严格退化等价）**
依次关闭需求剖面、需求奖励、鲁棒训练、策略证书、主动询问与需求监控后，`NeedGauge-RL` 分别退化为基线字典序目标、无需求条件奖励、标准约束 RL、`π_ref`、无询问策略与 v4 闭环；全部关闭时与 InstructGauge-WR 的 `WRC-ROS-7C` 逐动作等价。证明：每个关闭操作只把一个增强项替换为其基线常量或 `π_ref`，不改变底层 `A_adm`、CVC、前缀封闭分块与不可逆屏障；由定义 483 逐项对照即可。
