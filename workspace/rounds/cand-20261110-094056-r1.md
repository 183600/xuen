# 第 43 轮（新循环第 3 轮） · 隔离式证书内核 × 最小可验证产品：把 v7 飞轮收敛成可交付的「安全状态隔离舱」（四层架构 v8 / MCP 切片）

> 承接第 42 轮 v19（SCV × CKB × ECR）。第 42 轮自陈最大风险是「仿真偏差累积 + 检索幻觉」造成的静默失效，但还有一个它没承认的病：**架构已经膨胀到 10 个 IP、三段飞轮，工程上根本无法在真机上先站住**。本轮灵感词「状态隔离」「最小可行产品」正好是两把手术刀：**状态隔离**把证书从「一个巨大的共享可变状态」切成若干**不可互相污染的隔离舱（cell）**，用 rely-guarantee 契约把「谁能读、谁能写、坏了会污染谁」写死，让静默失效降级为**局部、可检测、可回滚**的故障；**最小可行产品**则把这套东西坍缩成一个能在真机上 4–6 周跑通的**最小可验证产品（MCP）**：单技能、单环境、L0 查表 + INT8 监控 + 独立安全监督器，RAG/组合/定点融合全部降级为「离线编译期可选件」而非「运行时必需件」。

## 0. 直觉与动机

**灵感 1（状态隔离 → 从「全局正确」到「局部正确 + 契约正确」）**：第 42 轮的 `cert_obj` 是一个共享可变大对象——感知、查表、监控器、自动机、课程引擎都能写它。这带来一种极坏的失效模式：**任何一处数值被污染，整个证书会带着「已认证」标记继续运行**。操作系统/微内核的直觉是：把状态按「失效影响半径」切舱，舱间只通过**只读、带版本号与 CRC 的快照**通信，监督器独立成最高优先级舱，任何舱故障都不能阻止它拉 SafeStop。验证成本从 `O(全系统)` 降到 `ΣO(舱) + O(接口契约)`。隔离分三层：**空间隔离**（MPU/内存分区、独立栈、CRC/canary、舱间无裸指针）、**时间隔离**（探索写影子快照，认证只读已提交快照，提交是原子切换）、**逻辑隔离**（类型化能力句柄，舱内私有不变式外部不可写）。

**灵感 2（最小可行产品 → 先定义「最小可验证产品 MCP」）**：第 42 轮是典型的「什么都想要」。MVP 的正确直觉不是砍功能，而是先回答：**让端到端证书在真机上被验证通过，最少需要哪几个舱？** 其余能力必须显式标注为 out-of-scope，并给每条缺失能力配一条降级路径（SafeStop / 人工确认 / 离线编译），而不是沉默缺失。形式化为带约束的最小化：`MCP = argmin Cost(S) s.t. Sound(S) ∧ Usable(S) ∧ Deployable(S)`。把 **soundness 当硬约束**，避免为了 Nominal 指标牺牲安全。

**灵感 3（耦合 → 隔离给 MVP 可切片性，MVP 给隔离优先级）**：隔离让每个舱可独立交付、独立回滚、独立做故障注入实验；MVP 则决定先隔离哪一圈——**决定安全的最小闭包**（监督器 S + L0 查表 + INT8 监控 + 快照总线）先做，知识库 CKB、RAG、组合代数这些「能力放大器」放到离线域，永远不能直接写在线证书状态，只能产出候选补丁，经隔离门校验后原子提交。

**架构 v8 的核心变化**：从「流水线」变成「隔离舱拓扑」。离线域（SCV/CKB，可失败、可慢、可重跑）与在线域（ECR/CAR/Supervisor，必须确定、必须可隔离）物理分离；在线域内 `P → M → A → S` 单向数据流，S 拥有唯一 SafeStop 权限与对任何舱的否决权。

## 1. 形式化定义（增量：定义 38–43）

**定义 38（证书状态隔离舱 Isolation Cell）**：设证书状态空间 `X` 与内存空间 `M`。隔离舱集合 `{Cell_i}_{i=0..n}`，其中 `Cell_i = (X_i, M_i, K_i, PrivInv_i, A_i, G_i)`，满足：
1. `X = ⊔_i X_i`（私有状态直和，跨舱状态只能以只读快照形式存在）；
2. `M_i ∩ M_j = ∅ (i≠j)`，`Cell_i` 独享栈与堆区；
3. `K_i` 是**能力集**，只包含允许读取的只读快照句柄与允许调用的纯函数，舱间无裸指针、无全局可写变量；
4. `PrivInv_i` 为舱内私有不变式；`(A_i, G_i)` 为其 rely/guarantee 契约（假设/保证）。
特设**监督器舱 `Cell_S`**：拥有唯一 `SafeStop` 写权限；其他舱可向它发请求，但不能关闭、降权或覆写它。

**定义 39（隔离契约与非干扰）**：`Cell_i` 满足 rely-guarantee 三元组 `{A_i} code_i {G_i ∧ PrivInv_i}`，其中 `A_i` 只允许依赖其他舱导出的 `G_j` 与不可伪造的只读环境量。**契约兼容**：对每条依赖边 `i→j`，要求 `G_i ⇒ A_j`。**非干扰（noninterference）**：若两次运行仅 `Cell_i` 的私有状态不同，则任意 `j≠i` 的证书导出观测相同，除非差异经由 `I_i` 的显式写发生。换言之，私有状态不泄漏、不越权污染。

**定义 40（一致快照与原子切面）**：快照 `S_v = (state_v, v, crc_v)`；`read()` 返回版本自洽的单个 `S_v` 或 `⊥`（seqlock 重试 / COW 原子交换），禁止撕裂读。**决策只允许消费一个快照**。**命题**：若每个舱的状态转移是「从 `S_v` 原子产生 `S_{v+1}`」，且任意证书决策只读单个 `S_v`，则该决策看到的是状态转移序列的一个线性化切面（consistent cut）；因此不存在「一半旧守卫 + 一半新阈值」的混合决策。

**定义 41（故障域与污染半径）**：故障模型 `F = {bitflip, exception, timeout, illegal_write, oom}`。依赖图 `D`：`i→j` 当且仅当 `j` 读取 `I_i`。污染集 `Cont(i)` 为故障 `i` 后可能被错误标记为 certified 的舱集合。**隔离 soundness** 要求：`Cont(i) ⊆ {i} ∪ Dep(i)`，且**不存在任何路径**从故障态不经重新校验到达 `Nominal`。恢复策略：从最近已验证快照重启 `Cell_i`；失败则由 `Cell_S` 强制 `SafeStop`。

**定义 42（最小可验证产品 MCP）**：设全组件集 `C`，候选子集 `S ⊆ C`。
`MCP = argmin_{S⊆C} [ Cost(S) + λ·|OOS(S)| ]`，
约束：
1. `Sound(S)`：端到端证书义务 `O(S)` 在真机上以置信 `1−δ` 全部被 discharged；
2. `Usable(S)`：`Nominal` 占比 `≥ ρ`（如 0.80），且关键技能成功率达标；
3. `Deployable(S)`：WCET、RAM、BOM、人周 `≤` 预算。
`OOS(S)` 为**显式范围外契约**（out-of-scope contract），逐条列出被推迟能力及其降级路径。MCP 不追求“功能全”，只追求“可被端到端验证且可交付”。

**定义 43（增量门与单调扩展）**：MCP 阶梯 `S0 ⊂ S1 ⊂ S2 ⊂ S3`。新增组件 `c` 仅当：(a) 新增义务 `ΔO` 全部 discharged；(b) `E87–E94` 无回归；(c) `OOS` 中的降级路径保留；(d) 跨舱契约差异经人工审计。定义**认证表面积** `CS = |跨舱契约条款| + 共享可写字节数` 与**隔离税** `T_iso = (Latency_iso − Latency_mono)/Latency_mono`。MCP 选择即是在 `CS`、`T_iso`、`Usable` 三者间的显式 Pareto 选择。

## 2. 产出设计（新增 IP-57/58/59 + 升级既有 IP）

### 2.1 IP-57 CERT-STATE-ISOLATOR（CSI，证书状态隔离器）
1. **舱划分编译器**：输入第 42 轮的证书对象与 CAR 转移表，按「失效影响半径」自动划分 `P/M/A/S/D` 五舱；输出每舱 `(A_i, G_i, K_i, PrivInv_i)` 与依赖图。
2. **能力化内存布局**：每舱独立 MPU region + 独立栈 + 只读快照句柄；舱内写只走本地 arena，跨舱写一律禁止；每舱定期 CRC + canary。
3. **隔离门（Isolation Gate）**：CKB/RAG/课程等离线产物只能产出**候选补丁**，必须通过「差集证明 + 全量验证集零违例 + 契约兼容检查」三关，才允许原子提交进认证快照仓库。
4. **故障注入测试床**：按定义 41 的 `F` 逐舱注入 bitflip/越权写/超时，度量污染半径与检测率，产出 `Cont(i)` 实测表。

### 2.2 IP-58 CERT-SNAPSHOT-BUS（CSB，证书快照总线）
1. **版本化 COW 快照**：`S_v = (state, v, crc, provenance)`；读无锁、写影子、原子交换；seqlock 兜底检测撕裂。
2. **能力句柄**：舱间只传 `Handle<S_v>`，不传裸指针；句柄只能读，不能改。
3. **原子提交协议**：`prepare → validate(ΔO + 契约兼容) → commit(v+1) → 旧版本归档`；任一环节失败回滚到 `S_v`。
4. **溯源与回滚**：每条快照带 `(git_commit, sim_config_hash, hw_version, isolation_contract_hash)`，支持审计与快速回滚。

### 2.3 IP-59 MCP-SLICER（最小可验证产品切片器）
1. **义务驱动切片**：把 v8 全组件图与端到端义务 `O(C)` 编译成集合覆盖/ILP：最小化 `Cost + λ|OOS|`，约束 `Sound/Usable/Deployable`。
2. **阶梯生成器**：输出 `S0`（L0 查表 + 监督器 + SafeStop）、`S1`（+ INT8 监控器）、`S2`（+ 偏移监控）、`S3`（+ 离线 CKB/RAG）四级切片及每级验收测试。
3. **降级矩阵**：对每个被裁掉的组件，生成其缺失时的降级路径（`SafeStop` / 人工确认 / 离线编译），写入 `OOS` 契约。
4. **消融计划**：自动生成 `E91` 的消融矩阵，回答「哪些组件是安全必需、哪些只是可用性放大器」。

## 3. 四层架构 v8（隔离舱拓扑）

```
离线域（可失败/可慢/可重跑，永不直写在线证书）
  IP-54 SCV ──► 每舱 A_i 仿真覆盖 + 反例 + 故障注入映射
  IP-55 CKB(RAG，仅编译期) ──► 候选模板/补丁 ──► 隔离门 ──► 认证快照仓库
  IP-59 MCP-SLICER ──► OOS 契约 + 降级矩阵 + S0..S3 阶梯
──────────────────────────────────────────────────────────────
在线域（单向数据流；跨舱只读 Handle<S_v>）
  Cell-P 感知(TRI-FUSE 定点 + LIO) ──► S_P(v)
        │
        ▼
  Cell-M 边际(L0 查表 + INT8 监控) ──► S_M(v)
        │
        ▼
  Cell-A 自动机(CAR 守卫/转移) ──► 候选动作 + 模式
        │
        ▼
  Cell-S 监督器(最高优先级/唯一 SafeStop) ──► 执行器
        │            ▲
        │            └── 契约校验: G_i ⇒ A_j, CRC, 看门狗, 心跳
        ▼
  Cell-D 偏移监控(只读/只告警) ──► IP-45 总线(快照版本+故障域)

```

## 4. 实验设计（E87–E94 硬门槛，承接 E79–E86）

| 实验 | 指标 | 门槛 |
|---|---|---|
| E87 隔离故障注入 | 逐舱 bitflip/越权写/超时：检测率、跨舱静默污染率、实测污染半径 | 检测率 100%；静默污染 0；污染半径 ≤ 1 |
| E88 快照一致性 | 并发压测撕裂读次数；快照读 p99 开销；线性化检查 | 撕裂读 0；p99 < 20μs；线性化通过 |
| E89 隔离税 | 端到端延迟/内存 vs 单体实现；认证表面积 CS | 延迟 < +15%；RAM < 64KB；CS 条款 ≤ 12 |
| E90 MCP 端到端真机 | 单技能单环境：不安全事件、Nominal 占比、MTBF、部署人周 | 0 起；Nominal ≥ 80%；≥ 200h；≤ 6 人周 |
| E91 消融实验 | S0/S1/S2/S3 的 Nominal、误 trip、成本；安全必需组件识别 | S1 相对 S0 Nominal 提升 ≥ 15pp；无安全回归 |
| E92 增量门 | 每新增组件的 ΔO 是否全 discharged、E87–E91 是否回归 | 100% discharged；0 回归 |
| E93 静默失效压制 | 注入 sim-real 偏差，隔离版 vs 单体版「污染后仍报 Nominal」率 | 隔离版 ≤ 单体版的 1/5；目标 0 |
| E94 交付与成本 | BOM、人周、Orin Nano/STM32H7 可运行；OOS 降级路径演练 | BOM ≤ 预算；≤ 6 人周；降级演练 100% 成功 |

回退：E87 隔离失效 → 退化为「双通道冗余 + 全量重校验」；E88 撕裂 → 单核串行化快照（换延迟）；E89 隔离税超预算 → 粗化为三舱（P / M+A / S）；E90 真机不达标 → MCP 再缩到 S0 + 人工确认；E91 无增益 → 承认 MCP=S0 并锁定；E92 回归 → 回滚上一提交并冻结版本。

## 5. 本轮最大风险

**一句话**：状态隔离会带来**隔离税与跨舱契约爆炸**，而 MVP 切片又可能因过度裁剪而丢掉真实长尾——最危险的不是「舱内不 sound」，而是「每个舱都局部正确、契约却在某个边界组合上漏了一条」，于是系统在 `Nominal` 里静默越界；因此 E87（污染半径）与 E92（增量门）必须作为红线，任何一条不达标就回退到更粗的隔离粒度并扩大 MCP 范围。

# 第 43 轮产物 · 创新点清单 v20：隔离式证书内核（CSI × CSB × MCP-SLICER）× 最小可验证产品（四层架构 v8）

### IP-58 CSB：一致快照与原子提交
```
def snapshot_read(handle):
    while True:
        v1 = load_version(handle)
        if v1 % 2 == 1: continue          # 写者持有奇数版本
        state = load_state_acquire(handle)
        crc = load_crc(handle)
        v2 = load_version(handle)
        if v1 == v2 and crc_ok(state, crc):
            return Snapshot(state, v1, crc)
        # 否则重试；超过 K 次返回 ⊥，由监督器降级
        if retries_exceeded(): return BOTTOM

def snapshot_commit(shadow, current, obligations):
    v_next = current.v + 1
    prepare(shadow, v_next)                     # 写影子，不动 current
    if not discharged(obligations, shadow):     # 增量义务
        rollback(shadow); return current
    if not contract_compatible(shadow, current):# 契约兼容
        rollback(shadow); return current
    publish_atomic(shadow, v_next)              # 原子交换
    archive(current)                            # 可回滚
    return shadow
```

### IP-59 MCP-SLICER：义务驱动切片与阶梯
```
def compute_mcp(components, obligations, budgets):
    # 变量 x_c ∈ {0,1}；目标：成本 + λ·被裁组件数
    # 约束1 Sound：每条端到端义务至少被一个选中组件闭环覆盖
    # 约束2 Usable：预估 Nominal(x) ≥ rho
    # 约束3 Deployable：WCET(x) ≤ W, RAM(x) ≤ R, BOM(x) ≤ B
    model = ILP(objective=sum(cost[c]*x[c] for c in components)
                        + lam*sum(1-x[c] for c in components),
                constraints=[cover(ob, x) for ob in obligations]
                          + [nominal(x) >= rho, wcet(x) <= W,
                             ram(x) <= R, bom(x) <= B])
    S_star = solve(model)
    OOS = [c for c in components if c not in S_star]
    degradation = {c: fallback_path(c) for c in OOS}
    return S_star, OOS, degradation

def build_ladder(S_star, all_components):
    # S0 最小安全闭包；S1 +INT8；S2 +偏移；S3 +离线CKB
    order = ['S0', 'S1', 'S2', 'S3']
    S0 = minimal_safe_closure(S_star)   # L0查表 + 监督器 + SafeStop
    ladder = [S0]
    for name, add in [('S1', 'int8_monitor'), ('S2', 'drift_monitor'),
                      ('S3', 'offline_ckb')]:
        ladder.append(ladder[-1] | select(add))
    return {n: s for n, s in zip(order, ladder)}
```

### 隔离组合定理（正确性核心）
```
Theorem (Compositional Soundness under Isolation):
若 (1) ∀i: {A_i} body_i {G_i ∧ PrivInv_i}（舱内局部正确）；
   (2) 依赖图存在拓扑序，或所有跨舱读均来自同一一致快照 S_v；
   (3) ∀i→j: G_i ⇒ A_j（契约兼容）；
   (4) Cell_S 唯一持有 SafeStop，且不可被其他舱关闭；
则全局运行满足 (∧_i PrivInv_i) ∨ SafeStop，且不存在未经重校验的 Nominal。

Proof sketch:
按一致快照的拓扑序对舱做归纳。基础：无前驱舱只依赖环境量，由 (1) 得 G_i。
归纳：若所有前驱 j 的 G_j 成立，由 (3) 得 A_i，再由 (1) 得 G_i ∧ PrivInv_i。
(2) 排除「读到一半旧一半新」的撕裂前提，使归纳前提在单快照内成立。
若任一 A_i 被违反，则 (4) 使 Cell_S 可立即撤销 Nominal 并进入 SafeStop；
因此任何未触发 SafeStop 的运行必满足全部 PrivInv_i。∎
```

# CAR：动作先写影子，监督器校验契约后才提交
def car_step(x_handle, cell_A, cell_S):
    S = snapshot_read(x_handle)              # 单一致快照
    cand = cell_A.transition(S)              # 只读 + 本地私有写

def certify_isolated(x_handle, guards, budget_us=200):

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性保证 |
|---|---|---|---|
| IP-57 舱划分 | 一次编译：`O(|V|+|E|)` 社区检测 | 依赖图 `O(|E|)` | 划分仅影响污染半径，不改变局部证明义务 |
| IP-57 隔离门 | `O(|Δ|·C_verify + N_val)` | 增量补丁 | 差集覆盖 + 全量零违例 + 契约兼容 ⟹ 提交不引入新违例 |
| IP-57 故障注入 | 离线 `O(N·|F|·|cells|)` 可并行 | 故障日志 | 实测 `Cont(i)` 上界；未覆盖故障类型显式列入 OOS |
| IP-58 快照读 | `O(1)` 平均，重试期望 `O(1)` | 双缓冲 `O(state)` | seqlock + CRC ⟹ 无撕裂读；`⊥` 触发降级 |
| IP-58 原子提交 | `O(|ΔO|)` 校验 | 影子副本 | prepare-validate-commit ⟹ 失败不改当前认证快照 |
| IP-59 MCP 切片 | ILP 离线，`O(2^{|C|})` 最坏，`|C|≤20` 可精确 | 模型 `O(|C|·|O|)` | 约束显式 ⟹ 解出的 S 满足 Sound/Usable/Deployable（模型内） |
| IP-51 CAR 隔离步 | `O(读出+转移+校验)` ≈ 16μs | 影子 `O(1)` | 监督器否决权 ⟹ 未校验动作不可达执行器 |
| IP-52 LCS 隔离档 | S0≈6μs / S1≈107μs | 同 L0/L1 | 决策等价按舱定义；预算耗尽单调降级 |
| IP-53 CMC 导出 | QAT 离线 | 模型 < 8KB | 学生边际 ≥ 教师下界（L_cert）+ 契约哈希绑定 |

**关键性质对比（单体 v19 vs 隔离 v20）**：单体版的正确性是「一个全局断言」，任一写错误都可能让整机带病报 Nominal；隔离版把正确性拆成 `Σ` 局部证明 + `O(|E|)` 契约证明，并把任何未证明状态强制导向 `SafeStop`。代价是 `T_iso` 与 `CS` 上升——这正是 E89/E92 要量化的东西。

## 4. MCP 阶梯与范围外契约（OOS）

| 阶梯 | 包含组件 | 预期能力 | 显式降级 |
|---|---|---|---|
| S0 | L0 查表 + `Cell_S` 监督器 + SafeStop | 单技能单环境、确定性场景 | 查表未命中 → SafeStop；无学习能力 |
| S1（建议 MCP） | S0 + INT8 监控器 | 覆盖 L0 未命中的连续状态 | 监控超时 → 降回 S0 或 SafeStop |
| S2 | S1 + 偏移监控（只告警） | 能发现分布漂移 | 只告警不重跑，需人工介入 |
| S3 | S2 + 离线 CKB/RAG（编译期） | 新任务热启动 | 检索失败 → 退回冷启动/手写模板 |
| v8 全量 | + 组合代数 + 定点融合 + 在线飞轮 | 多技能组合与持续进化 | 任一舱故障 → 收缩到 S1 |

> MCP 默认取 **S1**：理由由 E91 消融决定——若 S0 的 Nominal 已 ≥ 80% 则取 S0；若 S1 相对 S0 提升 < 15pp 则回退 S0。MVP 的可信度来自「显式 OOS」，而不是「假装什么都支持」。

| 契约爆炸：舱越细，`G_i⇒A_j` 条款越多、越易漏 | 高 | `CS` 预算硬约束（≤12 条）；契约自动生成 + 模型检查；E92 增量门逐条审计 |

## 7. 本轮最大风险

**一句话**：状态隔离会带来**隔离税与跨舱契约爆炸**，而 MVP 切片又可能因过度裁剪丢掉真实长尾——最危险的不是「舱内不 sound」，而是「每个舱都局部正确、契约却在某个边界组合上漏了一条」，于是系统在 `Nominal` 里静默越界；因此 E87（污染半径）与 E92（增量门）必须作为红线，任何一条不达标就回退到更粗的隔离粒度并扩大 MCP 范围。
