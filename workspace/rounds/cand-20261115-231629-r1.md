# 第 11 轮（本轮灵感：「商业模式」×「续航能力」）
> **基线**：第 10 轮 MetricVoiceGauge-STF-NRB-LS（定义 540–548；引理 87–91；实验 E571–E590）。
> 本轮纪律：**安全不可定价 + 续航即证书 + 契约可执行可审计**。两个灵感分别治理 v10 的两种债：**续航债**——LS 的 25W/内存是部署期静态配额，块证书不包含“完成本块并中止还够不够电”，低 SoC、热降频、执行器老化会让 50Hz 安全内核与停车不变式静默失守；**经济债**——v10 的规范/伦理已可计算，却没有“为谁服务、按什么契约、能量如何分配、责任如何留痕”的可执行层，ν-FAIR 仍是软启发式，商业压力可以绕过治理。铁律不变：新模块失效 ⇒ 注入声明中立元，行为对 v10 **等价**（SCR 默认契约）或**支配/更保守**（EE 的 Π_e），绝不行为漂移。

## 0. 直觉与动机

**灵感 1（续航能力 → 从静态功率配额到时间视界证书）**
直觉：v10 把误差界从全局标量局部化到空间足迹（β_STF），但没有把**能量**局部化到“这一块动作 + 中止路径 + 安全守卫”的时间视界。25W 是部署期平均功率，不是“这一块做完还停得下”的保证。真正危险的不是电池耗尽，而是**证书在耗尽前一直合格**：rollout 仍能算出漂亮轨迹，守卫仍假设自己以 50Hz 运行，直到热降频或电压跌落把安全内核拖垮——这是“合规地走向没电”。续航必须建模为**能量瀑布**：安全内核（感知、守卫、制动）是第一债权人，中止路径是第二，鲁棒预留是第三，服务任务只能用剩余。核心创新：**续航包络（EnduranceEnvelope, EE）**——把 SoC、电池健康、温度/可用功率、执行器效率纳入状态；每个块同时认证“完成 + 中止 + 守卫”三份能量与 `P_avail` 下的 50Hz 可调度性；不足则收缩块长（`K_E`）或进入 `Π_e`（回坞、降速、禁高功率），绝不带病执行。这把 v10 的静态 25W 预算升级为**时间视界内可完成、可中止、可守卫**的证书。

**灵感 2（商业模式 → 从伦理规范到可执行服务契约）**
直觉：v10 的 NRB 让“规范”变成了数据，但“为谁服务、承诺什么、能量预算多少、出了事谁担责”仍不在系统里。真实商业压力不会写在代码注释里，它会通过任务选择、会话排序、能量分配悄悄改变行为。与其把商业模式留成 PPT，不如把它编译成**可执行的契约数据**：每个服务会话携带 `C=(parties, scope, SLA, E_budget, N_ob, price, liability, consent, expiry, hash)`；**服务契约注册表（ServiceContractRegistry, SCR）**只在已经通过安全与续航认证的集合里做准入和能量分配；契约只能**移除任务**或**分配剩余能量**，绝不能放宽 `d_safe、停车不变式、N_safe、β_STF`。价格/影子价格 `λ_E` 只决定“做哪一单”，不决定“离人多近、留多少余量”；所有准入、能量预留、结算与责任写入价值台账 `Λ⁺`。v10 的 ν-FAIR 从软规范升级为可审计的**剩余能量 max-min 分配**。

**咬合**：EE 给出“做得到且停得下”的能量证书，SCR 给出“该不该做、为谁做、用多少电”的契约与分配，VL 给出“凭什么做、出了事谁负责”的留痕；共同把 v10 的 `Ĉ⁺` 升级为**续航-服务证书 `Ĉ_t^× = (ĝ_min, ê_max, γ̂_grasp, β_STF, n_t, Ê_t^+, κ_t)`**。关键不是把商业目标塞进控制目标，而是把它放在**字典序最后**：安全 ≻ 能量可行 ≻ 契约/效用。经济压力只能表现为“拒绝服务”，不能表现为“降低安全余量”。

## 1. 研究问题（轮次升级版）

- **Q1（续航证书）**：如何把静态功率配额升级为“完成 + 中止 + 守卫”的时间视界证书，使低 SoC/热降频/电池老化下**搁浅率为 0**、50Hz 安全内核 WCET 不破、能量利用率相对 v10 静态配额 ↑≥10%，且不确定遥测只能使动作集收缩？
- **Q2（服务契约）**：如何把服务承诺、能量预算、同意与责任编译成确定性准入与分配，使 (a) 任何价格/契约都不能放宽物理安全与 `N_safe`；(b) 契约失效在 1 块内退回 `C_0`（等价 v10 任务集）；(c) 多会话无能量双重支付、无饥饿，公平偏差 ≤5%？
- **Q3（经济-安全隔离与可审计）**：如何用价值台账把准入、预留、结算、责任、价格全部留痕，使篡改检出 100%、64 块内缺口自检、责任归因 100%，并证明审计面不回灌当期控制？

## 2. 设计原则（在 P13–P15 基础上新增 P16–P18）

**P16 安全不可定价律（Safety Not for Sale, EE/SCR）**
物理安全不变式、停车/中止点集、安全内核能量分区 `E_safe`、硬规范 `N_safe` 是**不可交易的硬约束**；任何契约、价格、SLA 或商业指标只能在已认证的安全-能量可行集 `F_×` 内做选择或移除任务。安全是约束，不是带价格的惩罚项；冲突时拒绝服务，而不是降低余量。

**P17 续航即证书律（Endurance-as-Certificate, EE）**
每个块必须携带“完成 + 中止 + 守卫 + 预留”的能量证书 `Ê_t^+`；静态 25W 配额不得单独作为续航证明。安全内核拥有**优先功率/能量分区**，低 SoC 或热降频先削减任务与高功率执行器，永不削减守卫。遥测过期/模型未知 ⇒ `Π_e`，绝不乐观外推。

**P18 契约可执行可审计律（Executable & Auditable Contract, SCR/VL）**
服务契约是带哈希的声明式数据，不是运行时代码；准入与能量分配必须确定性可重放。契约只能做减法（移除任务、限 scope/时间/同意）和分配（剩余能量），不能做加法（放宽安全/规范）。契约失效 ⇒ 默认单主体契约 `C_0`（等价 v10 任务集）；台账缺口 ⇒ 下块 `Π_e ∩ Π_r`；台账写入后置，不回灌当期控制。

## 3. 与基线的接口（如何退化）

- **EE 失效**（遥测过期/电池模型失配/热状态未知）⇒ `SoC_lo←0` 或 `P_avail_lo←0` ⇒ `Π_e`（K≤2、降速、禁高功率、回坞优先）：动作集 ⊆ v10，**支配** v10 的乐观执行；
- **SCR 失效**（契约表不可读/准入超时/版本偏斜）⇒ 默认契约 `C_0`（`E_budget=∞`、`N_ob=∅`、`scope=all`），任务集**等价** v10；非法/过期契约只拒绝该会话，不触碰安全层；
- **VL 失效** ⇒ 审计面冻结（不再写账），控制与证书不变，**等价** v10 控制；若 VL 报缺口/双重支付 ⇒ 下块 `Π_e ∩ Π_r`；
- **v10 原链**：STF 失效 ⇒ K=1/β=β_base；NRB 失效 ⇒ `Π_r`；LS/AC/ID/MW 失效沿 v10 六级退化 ⇒ v9 ⇒ v8 ⇒ v7 ⇒ v6。

## 4. 预期贡献

1. **续航包络证书**：把能量从静态配额局部化到“完成-中止-守卫”的时间视界，给出安全内核优先的能量瀑布与 `Π_e` 单调收缩（引理 92–93）；
2. **可执行服务契约**：把商业模式编译成契约数据 + 确定性准入 + 影子价格能量分配，并用字典序证明经济压力只能拒绝服务、不能侵蚀安全边界（引理 94、96）；
3. **价值台账与责任留痕**：能量预留/结算/责任/价格入 append-only 哈希链，证明无双重支付与缺口自检（引理 95）；
4. **E591–E610** 覆盖能量标定、低电/热压、契约压力、老化、长跑、多机共享与对抗能耗攻击。

## 5. 本轮最大风险

**一句话**：最大风险是**经济层与续航模型的联合失配**——电池/热模型偏低估计会高估 `E_service`，而价格压力又恰好把任务推向低 SoC、长视界、高语义新颖的角落，单步证书全部合格，系统却以合规的方式走向能量-安全边界的系统性耗竭。

# 第 11 轮产物 · 创新点清单 v11：**MetricVoiceGauge-EEC**（Metric Voice Gauge with Endurance Envelope & Executable Contracts）

> **继承纪律**：MetricVoiceGauge 九不变式（CVC-闭环、SpatialCert、RT-CVC、FaultCert、PrimitiveGraph、严格退化链、OTL、GCT、ER）与 v9 AC/MW/ID、v10 STF/NRB/LS/台账全部原样保留（IP-340–360）。新增三组件位于**块边界 / 慢循环 / 审计侧**，不进入 50Hz 物理控制：EE 失效 ⇒ `Π_e`（更保守，支配 v10）；SCR 失效 ⇒ 默认契约 `C_0`（等价 v10 任务集）；VL 失效 ⇒ 审计冻结（控制等价 v10）。v10 的最大风险（τ_sem 静默穿透）不被本轮直接拆除；v11 的职责是**不让经济压力与能量耗竭放大它**，并给低电量/热约束下的静默失守补上证书与退化路径。

**新增定义 549（续航状态）** `E_t=(SoC_t,H_t,Θ_t,P_avail(t),η_t)`，各分量以区间维护；`SoC_t^lo` 为荷电下界，`P_avail_lo` 为可用功率下界，`H_t` 为容量健康（随循环老化下降），`η_t` 为执行器效率。遥测新鲜度 `T_E=0.5s`；过期或模型未知 ⇒ `SoC_t^lo←0`、`P_avail_lo←0`（保守未知），不得外推。

**新增定义 550（能量瀑布与安全高级债权）** 定义块视界内的能量会计：
```
E_service(ζ,t) = SoC_t^lo − SoC_floor − E_safe(t) − ê_abort^hi(ζ) − e_res(t)
```
其中 `E_safe` 是安全内核（感知 + 守卫 + 制动）的**第一债权**，`ê_abort^hi` 是第二债权，`e_res` 是第三债权，`E_service` 是服务任务可用的残余。块可行必要条件为 `ê_ζ^hi ≤ E_service(ζ,t)`。契约只能对 `E_service` 做分配，任何情况下不得占用前三项。

**新增定义 551（块能量与中止能量）** `ê_ζ=Σ_k ê(a_k)+ê_cmp(ζ)+ê_sns(ζ)`，其中 `ê_cmp` 含 F̂_q rollout / STF / NRB 的计算能量，`ê_sns` 含感知。`ê_abort(ζ)=max_{k≤K} min_{p*∈P_abort(ζ)} [ê(state_k→p*)+ê_brake]`：取块内所有前缀状态的中止能量上确界，保证任何时刻中止都被覆盖。区间端点 `[ê_lo,ê_hi]` 经 E591 标定，覆盖真实消耗的概率 ≥1−ε_e。`e_res=e_res^0/H_t+e_res^model` 随健康下降而增大。

**新增定义 552（续航证书）** `Ê_t^+` 如符号表，`valid` 当且仅当：
1. `SoC_t^lo − SoC_floor ≥ ê_ζ^hi + ê_abort^hi + E_safe + e_res`；
2. `P_peak^hi + P_safe ≤ P_avail_lo`（安全内核功率分区优先）；
3. `Θ_head = Θ_max − Θ_t − ΔΘ(ζ) ≥ 0`（块视界热余量）；
4. `WCET_guard(P_avail_lo, Θ_t) ≤ 20ms`（50Hz 可调度性，含 DVFS/热降频）；
5. `n_e=1` 且遥测新鲜（定义 549）。
任一失败 ⇒ 证书不可得；不可得时按 `Π_e` 处理，不得“继续执行再看”。

**新增定义 553（续航门控与限制性剖面）** `K_E(t)=max{k≤K_max : Ê_t^+(prefix k, abort at k) valid}`；`K_eff^×=min(K_eff^{v10},K_E)`；若 `K_E=0` 或 `SoC_t^lo−E_safe ≤ SoC_floor+e_res`，进入 `Π_e`：`K_eff≤2`、`v_max←min(v_max,v_e)`、禁高功率执行器/大负载、禁新契约、优先回坞。`Π_e` 只收缩动作集，保留 v10 全部安全规范与 `Π_r`。

**新增定义 554（服务契约）** `C=(id, parties, scope, SLA, E_budget, N_ob, price, liability, consent, expiry, h_C)`：`parties` 为服务方/被服务方/责任方；`scope` 限定任务、区域、时段；`SLA` 只能在安全可行计划中承诺完成率/质量；`E_budget` 为该会话可用的服务能量（Wh）；`N_ob⊆N_defer`（只可包含 v10 可委托规范，`N_safe` 禁止进入契约）；`price` 为外部计价（可为 0 或负，表示公共服务）；`liability` 为责任上限；`consent` 记录/共享同意位；`expiry` 过期时间；`h_C` 为内容哈希。契约是数据，不含可执行代码，不写 `d_safe/κ/β`。

**新增定义 555（契约可行性、影子价格与准入）** `F_safe(t)` 为 v10/v11 已认证安全集，`F_E(t)` 为定义 552 可行的能量集，`F_C(t)` 为契约的 scope/时间/同意/预算约束；`F_×(t)=F_safe∩F_E∩F_C`。会话 `s` 可准入当且仅当存在一条块序列完全落在 `F_×`。分配求解
```
max_x  Σ_i price_i·x_i − λ_E·Σ_i E_i^hi·x_i − L(x) − φ_fair(x)
s.t.   x_i∈{0,1},  Σ_i E_i^hi·x_i ≤ E_service(t),  x_i=1 ⇒ s_i∈F_×
```
`λ_E` 为能量约束的对偶/影子价格；`L(x)` 为契约责任期望；`φ_fair` 为 max-min 公平偏差（仅在同一 `F_×` 内）。会话数≤8 时精确枚举/DP。**价格只改变 `x`，不改变 `F_safe` 或安全余量**。SCR 失效时使用 `C_0`，此时 `F_C=全集`，任务集等价 v10。

**新增定义 556（续航-服务证书）** `Ĉ_t^×=(ĝ_min,ê_max,γ̂_grasp,β_STF,n_t,Ê_t^+,κ_t)`，`κ_t=(C_id,h_C,admission_id,n_e)`。`valid` 当且仅当 v10 `Ĉ_t^+` valid ∧ `Ê_t^+` valid ∧ `κ_t` 与当前活跃契约/准入记录一致；若契约过期/非法 ⇒ 仅拒绝该会话（不触碰安全层）；若 SCR 失效 ⇒ 用 `C_0` 重验。块证书失效与单步条件同样触发 M₀ 硬检查（v10 引理 82/81 原样）。

**新增定义 557（价值台账）** `Λ⁺` 在 v10 `Λ` 上扩展记录：
```
rec = H(prev ‖ t ‖ ζ_id ‖ h_C ‖ admit/deny ‖ E_res^hi ‖ E_settle ‖ λ_E ‖ liability ‖ utterance)
```
准入时**预留** `E_i^hi`，块结束时**结算**实际能量；`append-only` 哈希链（κ_h=256），块边界批量写，每 `C_w=64` 块校验点。不变量：`Σ_{active} E_res^hi + E_safe + e_res ≤ SoC_t^lo−SoC_floor`（无双重支付）。缺口/双花/校验失败 ⇒ 下一块强制 `Π_e∩Π_r` 直至重验；VL 不可写 ⇒ 审计冻结，控制面不回灌。

## 2. 形式化定义（要点与升级）

**升级 v10 定义 543**：v10 `Ĉ_t^+ valid` 仍为必要条件；v11 块有效 ⇔ `Ĉ_t^+ valid ∧ Ê_t^+ valid ∧ κ_t 匹配`。`ĝ_min`、`ê_max` 的计算不变，但 `β_STF` 的语义前提由 EE 保证“守卫在块视界内可运行”；若 `Ê_t^+` 不可得，则 `Ĉ_t^×` 直接失效。

**升级 v10 定义 539（有效块长，v11）**：
```
K_eff^×(t) = min( K_eff^{v10}(t), K_E(t) )
```
`K_E` 单调：SoC 下降、温度上升、健康下降、预留增大都只会减小 `K_E`。当能量充足且热/功率余量满足时，`K_E=K_max`，`K_eff^×=K_eff^{v10}`，行为等价 v10。

**安全-经济字典序**：对任意两个候选 `π₁,π₂`，先比较 `F_safe`，再比较 `F_E`，最后才比较效用 `U`；不存在用 `U` 补偿前两层失败的标量权重。实现上必须使用硬约束/字典序，不得用有限大罚项 `M·1[violation]`（引理 96 给出反例）。

class EnduranceEnvelope:
    def __init__(self, SoC_floor, P_safe, T_E=0.5):
        self.SoC_floor, self.P_safe, self.T_E = SoC_floor, P_safe, T_E
        self.state = None
        self.e_res0 = 0.0

    def update(self, telemetry):                 # 5Hz：SoC/H/Theta/P_avail/eta 区间
        self.state = telemetry.intervals()
        if not telemetry.fresh(self.T_E):
            self.state.SoC_lo = 0.0              # 未知 ⇒ 保守
            self.state.P_avail_lo = 0.0

    def e_res(self):
        s = self.state
        return self.e_res0 / max(s.H, 1e-3) + s.e_res_model

    def energy_cert(self, chunk, state):
        s = self.state
        e_chunk = chunk.sum_energy_hi()          # 定义 551 前缀和
        e_abort = chunk.max_abort_energy_hi()    # 所有前缀状态的中止上确界
        e_safe = chunk.e_guard + chunk.e_sense + chunk.e_brake
        ok = (s.SoC_lo - self.SoC_floor
              >= e_chunk + e_abort + e_safe + self.e_res()
              and s.P_peak_hi + self.P_safe <= s.P_avail_lo
              and s.theta_head(chunk) >= 0
              and wcet_guard(s.P_avail_lo, s.Theta) <= 0.020
              and s.n_e == 1)
        return EnergyCert(e_chunk, e_abort, e_safe, self.e_res()) if ok else None

    def effective_K(self, chunk_prefix, K_v10):
        K_E = 0
        for k in range(1, min(K_v10, self.K_max) + 1):
            if self.energy_cert(chunk_prefix[:k], self.state):
                K_E = k                          # 单调：可用二分/前缀和
        return min(K_v10, K_E)

    def pi_e(self):
        return RestrictiveProfile(K_max=2, v_max=self.v_e,
                                  no_high_power=True, no_new_contracts=True,
                                  dock_priority=True)


class ServiceContractRegistry:
    def __init__(self, ledger, C0):
        self.ledger, self.C0 = ledger, C0
        self.healthy = True

    def admit(self, sessions, e_service, t):
        if not self.healthy:
            return self._allocate(sessions, self.C0, e_service)  # ≡ v10 任务集
        feasible = []
        for s in sessions:
            if s.contract.valid(t) and s.contract.scope_ok(s.task) \
               and s.energy_cert is not None and s.safe_cert is not None:
                feasible.append(s)               # F_× = F_safe ∩ F_E ∩ F_C
        # 会话数≤8：精确枚举/DP；λ_E 由能量约束对偶或边际价值给出
        x = exact_or_dp(feasible, budget=e_service, lam=self.lambda_E(t))
        for s in x:
            self.ledger.reserve(s.id, s.energy_cert.e_chunk_hi, t)
        return x

    def settle(self, s, e_actual, t):
        self.ledger.settle(s.id, e_actual, t)
        if e_actual > s.energy_cert.e_chunk_hi + EPS:
            return 'pi_e'                        # 模型失配 ⇒ 下块收缩
        return 'ok'

## 4. 推导

**引理 92（续航证书的完成-中止安全性）** 设 (A1) 能量区间标定覆盖真实消耗：对认证集内任意动作/块，`e(π)∈[ê_lo,ê_hi]` 的概率 ≥1−ε_e（E591）；(A2) 电池/热/功率下界可信：`SoC_t^lo≤SoC_t`、`P_avail_lo≤P_avail`、`Θ_head` 覆盖块视界（E592）；(A3) 中止点集与中止轨迹经 v10 认证。若 `Ê_t^+` valid，则执行该块并在任一前缀中止，最终 `SoC ≥ SoC_floor` 且 50Hz 守卫可调度，概率 ≥1−ε_e−ε_sched。证明：`ê_abort` 取所有前缀状态的上确界，故任一实际中止能量 ≤`ê_abort^hi`；已执行前缀能量 ≤`ê_ζ^hi`；由定义 552 条件 1，`SoC_t^lo−SoC_floor ≥ ê_ζ^hi+ê_abort^hi+E_safe+e_res`，实际消耗不超过上界，故剩余电量始终覆盖 `E_safe` 与地板；条件 2–4 保证守卫功率分区、热余量与 WCET；并集界收尾。∎

**引理 93（续航包络的单调收缩与 v10 支配）** (a) `SoC_t^lo` 下降、`Θ_t` 上升、`H_t` 下降或 `e_res` 增大 ⇒ `K_E` 与 `F_E` 非增，`Π_e` 的动作集是原动作集的子集；(b) 恒有 `K_eff^×≤K_eff^{v10}` 且 `F_×⊆F_safe`，故 v11 的物理行为集 ⊆ v10 的安全可行集；(c) 当 SoC/功率/热余量充足时，定义 552 的条件 1–4 自动松弛，`K_E=K_max`，若 SCR 使用 `C_0` 则 `F_×=F_safe`，行为等价 v10；(d) EE 失效/未知 ⇒ `SoC_lo=0` 或 `P_avail_lo=0` ⇒ `Π_e`，比 v10 的乐观执行更保守（支配），不会行为漂移。证明：能量会计对 `SoC_lo` 单调、对 `e_res` 反单调；`K_E` 取满足条件的最大前缀，条件随 k 单调收紧；失效注入直接使条件 1/2 失败。∎

**引理 94（契约层的安全不可定价与审计隔离）** (i) `C` 的域不含 `N_safe`、`d_safe`、停车不变式、`β_STF` 下界与 `E_safe`；`F_C` 只做交集，故 `F_×=F_safe∩F_E∩F_C⊆F_safe`。(ii) 对任意价格/责任/公平项，`argmax_{π∈F_×}U(π)⊆F_×`；不存在 `π∉F_×` 被选中，因为它在约束外。(iii) SCR 失效返回 `C_0`，`F_C=全集`；结合 (c) 得任务集 ≡ v10。(iv) `Λ⁺` 写入发生在块执行之后；其唯一反馈是下一块的缺口/双花标志触发 `Π_e∩Π_r`，不改变当前块的执行与证书。证明：集合包含 + 字典序 + 代码路径隔离。活性注记：`F_×` 为空时执行 v10 兼容的安全停驻/回坞并语音披露（E594）。∎

**引理 95（能量不可双重支付与价值台账一致性）** (i) 每次准入原子地预留 `E_i^hi`，不变量 `Σ_{active}E_res^hi+E_safe+e_res≤SoC_t^lo−SoC_floor` 在预留/结算前后保持；结算用实际值替换预留，若实际超过预留则触发 `Π_e`。(ii) `Λ⁺` 为 κ_h=256 位哈希链，任何历史删除/改写以 ≥1−2^{−256} 概率被离线复盘检出；每 64 块校验点使在线缺口至多存续 64 块即触发 `Π_e∩Π_r`。(iii) 写入摊销 O(1)，在 VL 契约预算内（≤0.1ms/块边界）。证明：预留事务的原子性 + 区间上界 + 哈希碰撞概率；与 v10 引理 90 同构。∎

**引理 96（价格不能穿越安全边界 / 无有限罚项替代）** 令 `U_λ(π)=price(π)−λ_E e(π)−L(π)−φ_fair(π)`。对任意 `λ_E≥0`，`argmax_{π∈F_×}U_λ⊆F_×`；能量稀缺时 `λ_E` 上升，可行服务集收缩（拒绝服务），而 `F_safe` 与安全余量不变。反之，若实现用有限罚项 `U=revenue−M·1[π∉F_safe]`，则存在 `revenue>M` 使违规成为最优——故必须用硬约束/字典序，不得用加权和。证明：约束优化与罚函数优化的标准反例；`F_×` 与 `λ_E` 无关。∎

**推论 1（经济压力表现为服务拒绝，而非安全降级）** 由引理 94+96：任何商业压力只能改变 `x`（准入/任务选择）与 `λ_E`，不能改变 `d_safe`、`β_STF`、`E_safe`、`N_safe`；因此在同一条 v10 安全证书下，v11 的物理安全集不缩小也不扩大，经济性只决定“做不做、为谁做”。∎

## 8. 本轮最大风险

**一句话**：最大风险是**经济层与续航模型的联合失配**——电池/热模型偏低估计会高估 `E_service`，而价格压力又恰好把任务推向低 SoC、长视界、高语义新颖的角落，单步证书全部合格，系统却以合规的方式走向能量-安全边界的系统性耗竭。
