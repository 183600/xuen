# 第 8 轮 · CARE-VLA：把“最后一公里”做成接触-撤销感知的闭环

> 检索/复核日期：2026-10-27（UTC）。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮是灵感循环的第 2 轮，接续第 7 轮 PILOT-GPR；三个灵感词是「移动操作」「力觉传感」「奖励设计」。
>
> 我先按官方事实逐一压力测试这三个词，结果有两个必须改写：**UniBot 的“移动操作”不是移动基座**（演示里基座与下半身基本冻结），**“力觉传感”在 API 与数据集里根本不存在**（没有力/力矩/触觉通道）。只有“奖励设计”有官方稠密信号，但排名又是**成功率优先、步骤分只做同分决胜**。于是本轮主判断从“攻终局放置”进一步收缩为：**在强基座外挂一个同 checkpoint 的“接触-撤销感知最后一公里闭环”（CARE-VLA），用残差接触代理代替力传感器，用评分步骤过程奖励做选择与恢复，用历史条件化处理移动目标与人为撤销；不做新基座、不做移动基座、不做独立 PRM 模型。**

## 0. 本轮先纠错：三个会把方案带偏的“事实”

### 0.1 榜单的步骤分是成功率的线性缩放，不是独立测量

我重新解析了 `leaderboard_data.json` 的 8 个模型 × 32 任务。对每个模型单独做 `step_score ~ success_rate` 回归，结果全部是：

```text
step_score = k_model × success_rate + b_model
R² > 0.999999，|b| < 0.005
```

| 模型 | 成功率 | 步骤分 | k | R² |
|---|---:|---:|---:|---:|
| MolmoAct2 | 29.7 | 39.0 | 1.3133 | 0.99999963 |
| WALL-OSS-0.5 | 28.5 | 38.9 | 1.3649 | 0.99999983 |
| DreamZero | 27.9 | 37.9 | 1.3584 | 0.99999992 |
| Spirit-v1.5 | 25.9 | 34.4 | 1.3283 | 0.99999993 |
| DM0 | 23.5 | 31.7 | 1.3491 | 0.99999991 |
| PI-0.5 | 22.8 | 30.6 | 1.3420 | 0.99999989 |
| GigaBrain-0 | 22.6 | 29.5 | 1.3053 | 0.99999987 |
| GR00T N1.5 | 20.5 | 28.1 | 1.3707 | 0.99999989 |

这不是“步骤分和成功率相关”，而是**步骤分被生成脚本写成了成功率的固定倍数**。配合另外三个证据：榜单 raw HTML 仍写「即将发布 Coming Soon」；详情页的视频全部是「测试视频占位」；JSON 的 `generated_from` 仍是 `gen_leaderboard.py`——结论只能有一个：**这是预发布/演示榜单，不是可用的真实评测数据。**

这直接推翻了第 7 轮的一个推论：上一轮说“步骤分平均比成功率高约 8.6pp，说明多数失败发生在最后一步”。那个 8.6pp 只是 `(k−1)×success` 的算术产物，**不能用来推断失败分布**。用户看到的“榜首成功率也不到 30%”同样来自这份预览数据；它可能接近真实难度，但在官方发布真实榜单前，只能当“难度先验”，不能当“谁强谁弱”或“瓶颈在哪”的证据。

### 0.2 官方排名是成功率优先，步骤分只做同分决胜

中文手册写得很清楚：

> 实时榜单按 32 个任务的 **总平均成功率** 进行排序，成功率相同时按总平均步骤分排序，若仍相同，则提交日期较早的模型排序靠前。

这和首页“按平均成功率与步骤分综合排序”的模糊说法不同。手册是权威规则，因此：

- **第一目标永远是成功率**；步骤分只在成功率打平时才有用。
- 官方 `score_steps` 仍然极有价值——它是**稠密的步骤标签/过程奖励**，不是主排名目标。
- “终局步骤占 39.8%”仍是结构事实：成功要求所有步骤完成，终局是 32/32 任务的闸门；但“失败主要发生在终局”是待验证假设，不是已证事实。
- 不应该为了步骤分去牺牲成功率；也不应该把“最后一步”当成唯一战场。

### 0.3 “移动操作”在 UniBot 里不是移动基座

我原本以为“移动操作”会指向 G1 的 base/pivot，甚至考虑过移动基座策略。数据把这条路堵死了：

- PlugCharger 首个数据文件 130,958 行、269 个 episode：`action.pivot` **严格恒为** `[0, 0, 0, 0, 0.15, 0, 0.74]`；`action.base_command` **严格恒为** `[0, 0, 0, 0.74]`；`action.lower_body` 与 `observation.state.lower_body` 逐帧相同。
- HangCup 的 `meta/stats.json`：`action.pivot` 均值 `[~0, ~0, 1.66e-5, 0, 0.15, 0, 0.7384]`，std `[2.1e-5, 4.6e-7, 0.00717, 0, 2.8e-4, 0, 0.00639]`；`base_command` 的 vx/vy 近零，angle 跨 episode 有 ±0.8，height 0.65–0.74。角度变化更像不同 episode 的初始朝向，而不是演示中的主动转向。
- 换句话说：**演示中没有主动导航/移动基座**。评测任务是桌面操作，不是 loco-manipulation。

所以「移动操作」只能重解释为三件事：

1. **移动目标**：T24 传送带上的食物在动；human 备注里也有“可乐/薯片快到了然后放回起点”。
2. **移动干扰**：5 个泛化轴中的人为干扰轴（每任务 2/10 次，占 20%）大量是“把物体平移/拿走/撤销”；这不是基座移动，而是目标与场景在动。
3. **移动视角**：腕部相机随手臂运动，遮挡/视角变化是“移动”的另一层含义；用 `obs_delta_indices` 做短历史，比学一个 base policy 更直接。

因此本轮**不做移动基座**。这不是保守，而是把预算从“评测不考、数据没有”的自由度上撤回来。WholeBodyVLA 之类的人形 loco-manipulation 工作很漂亮，但它的动作空间、场景和 UniBot 不匹配；本轮只把它当“反例/边界”。

### 0.4 “力觉传感”在 API 与数据里不存在

这是第二个必须改写的词。官方 API 的观测只有：

- 4 路 RGB：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`（480×640）；
- 双臂关节 7 维或 EE 位姿 6 维、夹爪 1 维、下半身 15 维、语言 1 条；
- 数据集里还有 torso 系 EE、waist、state_torso、state_d435、`recomputed_ee_valid`，但 API 不暴露；
- **没有 force、torque、tactile、current、contact microphone**。

数据集的 `action.gripper_controls` 从字段形态看更像遥操作的 trigger/squeeze，不是力反馈；G1 的关节力矩也没有出现在接口里。所以任何“力觉传感”主张都必须写成**代理/蒸馏**，不能写成“我们用了力传感器”。

本轮可用的代理信号有四类：

| 代理 | 定义 | 物理含义 | 风险 |
|---|---|---|---|
| 跟踪残差 `r_t` | `||a_t − s_{t+Δ}||`（双臂关节或 EE） | 控制器跟不上/被接触阻挡 | 控制器滞后、减速、采样延迟都会造成残差 |
| 夹爪 stall | `a_gripper − s_gripper` 在闭合阶段的持续差 | 夹持受阻/物体宽度 | 夹爪标定、物体弹性 |
| 腕部视觉接触 | 腕相机中目标/工具的相对位姿突变、遮挡、形变 | 接触/插入/滑移 | 透明/反光/小物体不可靠 |
| EE 位姿残差 | 指令 EE 与实测 EE 的差 | 外部约束/碰撞 | 运动学标定、base 系漂移 |

- **在线可用性**：离线用 `a_t` 对齐 `s_{t+3}` 是为了估计控制延迟/接触；在线不能偷看未来。PCO 只能用已实现的延迟残差（`a_{t-3}` vs `s_t`）、一步跟踪误差（`a_t` vs `s_{t+1}`）、夹爪命令-状态差和腕部视觉。BoN 选新 chunk 时只能用上一 chunk 的已实现残差；新 chunk 的残差要执行后才知道。

我在 PlugCharger 上做了个小试（只用于提出假设，不作为结论）：

- 269 个 episode、130,958 帧；`action[t]` 与 `state[t+3]` 最匹配：lag=3 的平均绝对误差 **0.01544 rad**，lag=0 是 **0.02347 rad**（约降 34%）。
- 对双臂 14 维残差取 L2、5 帧滑动平均后，**233/269（86.6%）的 episode 最大值落在最后 30%**；max/median 均值 **3.17**；最后 20% / 最初 20% 的残差比均值 **1.50**；与“任一把夹爪 <2（holding）”的相关系数均值 **0.304**。
- 这说明残差在“接近-接触-插入”的后段确实变大，和接触事件同步；但它同样可能是控制器在减速/换向时的滞后。**单任务、无 ground-truth force、无跨任务校准，不能把它当力传感器。**

所以本轮把“力觉”改写成**本体感受接触观察器 + 残差力代理（PCO/RFP）**：不声称测力，只声称“从可观测的本体/视觉信号里估计接触概率、接触相位与受阻程度”，并用它做减速、微调、重试、chunk 选择。FD-VLA 的“无传感器力蒸馏”、ForceVLA2 的“力感知专家”、HapticVLA 的“接触门控 + reward-weighted flow matching”都支持这个方向，但它们要么需要额外力数据，要么需要触觉硬件；我们只能取其中“接触表示 + 门控 + 奖励加权”的部分。

### 0.5 奖励设计有官方稠密信号，但必须防“撤销”

官方 `score_steps` 给了 32 个任务的逐步分值（满分 100），这是现成的 dense reward/step label。它的问题是：

- 排名是成功率优先，步骤分只在同分时用；**不能把步骤分当主目标**。
- 步骤分是“完成到哪一步”的分数，不区分“做完又撤掉”。而 human 备注里明确有撤销剧本：T27“叠了第二个之后拿下第二个”、T19“拉上拉链之后拉开”、T14“拧开盖子之后拧动回来”、T17“笔盒合上之后手动打开”、T16“将叠完的毛巾翻开”。
- 一个只会“往前走”的策略，可能在 human 轴被撤销后停在“看起来完成、实际失败”的状态；成功率不认部分分，只认最终状态。

因此本轮把“奖励设计”落到**评分步骤过程奖励头（PRM-S）**上：

- 输入：历史观测/动作/接触代理 + 当前步骤图节点；
- 输出：步骤索引、步骤内进度、**撤销/回退概率**、最终成功概率；
- 训练：官方 `score_steps` 做步骤标签；human 备注 + 反向动作做撤销增广；PCO/RFP 做弱接触标签；
- 使用：**reward-weighted flow matching**（RWFM）给动作块加权；**best-of-N** 选 chunk；**reversal-triggered recovery** 触发 NRB；不单独跑一个 PRM 模型（单模型合规）。
- 证据：RoVer（PRM 作为 test-time verifier，best-of-N，+17.3%）、DiVeR（decision-critical PRM，+13.6%）、VeriVLA（latent verifier，+14.7%，326ms）、Robo-Dopamine 2.0（history/OOD-aware PRM，+10.6% OOD）、HapticVLA（safety-aware reward-weighted flow matching）。这些结果不能直接迁移，但方向一致：**过程奖励最适合做推理时的选择/恢复，而不是替代成功率。**

### 0.6 公开模型证据：强在语义/空间，弱在接触/时序/恢复

榜单数字不可信，但模型家族的公开论文/模型卡仍能说明架构倾向。我的判断是：

- **MolmoAct2**：Molmo2-ER + 深度/动作推理 + flow-matching action expert，空间 grounding 强；短板在接触力、推理延迟。
- **WALL-OSS-0.5**：4B、单帧输入、固定 26-D 动作、无时序记忆；短程精度和部署友好，长程/移动目标/撤销弱。
- **DreamZero**：14B World Action Model、视频扩散、7Hz 闭环，物理泛化强；但重、可能幻觉、无真实力觉，不适合做本轮基座。
- **Spirit-v1.5**：Qwen3-VL-4B + DiT、多样数据；RoboChallenge 表现强；接触/长程仍是短板。
- **DM0**：embodied-native、操作+导航统一、flow matching；高效，但小模型容量和接触力有限。
- **PI-0.5**：开放世界 co-training、语义子任务；强语义，弱接触；且不是 G1/Dex1 专用。
- **GigaBrain-0**：world-model 生成数据、RGBD/CoT；数据引擎思路可借，但 API 没有 RGBD，模型也重。
- **GR00T N1.5**：3B humanoid foundation、flow matching；跨 embodiment 强，但模型卡写的是非商用许可，使用前必须核对。

这不是“头部模型都不行”，而是：**基座的语义/空间能力已经足够好，真正缺的是最后一公里的接触、时序、验证与恢复。** 这也解释了为什么“再换一个更大的基座”不是本轮最划算的押注。

## 1. 三个灵感词，各自钉到可执行的东西上

### 1.1 移动操作 → 移动目标/干扰下的时序跟踪

不做基座，做三件事：

1. **T24 传送带**：目标在动，抓取点必须在“未来时刻”而不是“当前帧”。用 `obs_delta_indices` 堆最近 K 帧（K=4–8），让策略/MTT 估计目标速度与到达时间；动作块可以条件化“拦截点”。
2. **人为干扰轴**：每任务 2/10 次，占 20%；备注里大量是“移动物体/拿走/撤销”。这不是导航，而是**目标状态在 episode 中变化**。用历史条件化的 PRM-S 检测“目标被移动/步骤被撤销”，触发重定位或重做。
3. **移动视角**：腕相机随手臂运动，遮挡/尺度变化大；用短历史 + 相对位姿，而不是单帧全局外观。

这条线的价值不在“移动”本身，而在**时序记忆**：WALL-OSS 这类单帧模型在静态短任务上很强，但遇到“目标刚被移走/刚被撤销”就会失效；加一层历史条件化，是低成本、跨任务的补强。

### 1.2 力觉传感 → 本体感受接触观察器 + 残差力代理

不做“力传感器”，做 `PCO/RFP`：

- 输入：最近 K 帧的双臂关节/EE、夹爪指令与状态、腕部图像、动作块、步骤图节点；
- 输出：接触概率 `p_contact`、接触相位（接近/接触/插入/保持/释放）、受阻标量 `f_proxy`、滑移/未到位概率；
- 监督：跟踪残差、夹爪 stall、腕部视觉接触的弱标签；可选：少量带力传感器的实验室数据做蒸馏（默认关闭，等政策）；
- 使用：接触门控的减速/微调、插入深度校验、SVL 的“没插进去就重试”、BoN 的接触一致性评分；
- 关键：**永远称“proxy”，不称“force”**；在论文/模型卡里写清楚没有力传感器。

这条线是本轮最差异化的研究点：公开的 ForceVLA2/HapticVLA 需要力/触觉硬件，FD-VLA 做无传感器蒸馏但需要教师；我们只有 33k 无力的 G1 演示，所以“从本体残差里学接触”是唯一可行且可验证的路径。

### 1.3 奖励设计 → 评分步骤过程奖励 + 撤销感知 + 奖励加权

不做“独立 PRM”，做同一个 checkpoint 里的 `PRM-S`：

- 步骤标签来自官方 `score_steps`；步骤边界用动作/夹爪/视觉变化点做弱分割，再人工抽检；
- 撤销标签来自 human 备注 + 反向动作 + 仿真回放；训练时给低权重，避免破坏正常轨迹；
- 输出 `p(step)`、`progress`、`p(reversal)`、`p(success)`；
- 用 `p(success)` 和 `progress` 做 chunk 的 advantage，喂给 RWFM；用 `p(reversal)` 触发 NRB；用 `p(step)` 做 SSG 的校验；
- 单模型合规：PRM-S 是基座特征上的小头，不是第二个模型；检索库是数据，不是模型。

这条线的价值：**把官方评分结构变成可微/可打分的中间信号，但不让模型为了步骤分牺牲成功率。** 成功率优先，过程奖励只做“选择/恢复/加权”，这是和官方排名一致的用法。

## 2. 本轮主判断：不是更强的基座，而是更强的最后一公里

把上面的证据合起来，我的判断是：

1. **基座不是当前最稀缺的变量。** 公开模型在语义/空间上已经很强；榜首约 30% 的成功率（预览，仅作难度先验）说明任务很难，但**不能**据此推断失败位置。结合公开模型的架构瓶颈（单帧/少接触/少恢复）和我们的残差小试，更合理的假设是失败集中在执行末端。换一个更大的基座，收益不确定，成本和许可风险都高。
2. **接触、时序、验证、恢复是跨任务复用的。** 32 个任务里，至少 14 个的终局含插入/闭合/拉链/锁合/倾倒/注射（按终局动作粗分，545/1275 终局分）；另外 18 个是放置/堆叠/悬挂/取出（730/1275）。两条线都需要“做到位/没做到就重试”，而不是只做一次开环预测。
3. **无真实力觉，反而给了方法空间。** 如果所有人都有力传感器，残差接触代理没有意义；但 UniBot 没有，谁能把本体残差/夹爪 stall/腕部视觉变成可靠的接触观察，谁就多一层闭环。
4. **撤销是 human 轴的结构性难点。** 5 个轴里人为干扰占 20%，备注里大量“先完成再撤销”。一个 history-conditioned 的 PRM-S 可以同时用于“检测撤销”和“恢复”，比单独做扰动分类更划算。
5. **单模型规则排除了“外挂一个 PRM”的捷径。** 必须把接触/进度/撤销做成同一 checkpoint 的辅助头；这反而让方案更干净：一个基座、一组头、一个控制循环。

所以本轮的主押注是：

> **CARE-VLA：在强基座（WLA-1.0-Base / MolmoAct2 / WALL-OSS-0.5）上，增加同 checkpoint 的 PCO/RFP 接触观察 + PRM-S 评分步骤过程奖励 + MTT 时序记忆，用接触门控、best-of-N 和撤销恢复把“最后一公里”做成闭环；不做新基座、不做移动基座、不做独立 PRM。**

预期收益（可证伪，不是承诺；注意 320 次试验下单次 +3pp 统计上不可判定，以下主要是机制/任务级目标）：

- 接触关键任务（T10/T26/T19/T23/T31 等）成功率 +3–5pp；
- human 轴撤销场景的恢复率 +10pp；
- 步骤分随成功率小幅提升（同分决胜有意义），但不以步骤分为主目标；
- 代价：推理延迟增加（PCO/PRM 头 + BoN），需要控制在 chunk 预算内。

## 4. 证据链：为什么是这些组件，而不是别的

- **接触代理**：PlugCharger 小试（lag=3、残差后段峰值、夹爪 holding 相关）+ FD-VLA/ForceVLA2/HapticVLA 的公开结果；但小试只证明“有信号”，不证明“可迁移”。本轮必须补 T10/T26/T19/T23 的跨任务校准。
- **过程奖励**：RoVer/DiVeR/VeriVLA/Robo-Dopamine 2.0 都显示 PRM/verifier 在 test-time 选择/长程任务上有收益；但它们大多假设可以单独跑 verifier。我们的约束是单模型，所以必须做头，不能做独立模型。
- **时序记忆**：WALL-OSS 单帧、DreamZero 视频世界模型、MTT 的相对运动；我们不需要 14B 视频模型，只需要“最近 K 帧 + 目标相对运动 + 撤销检测”的小历史。
- **移动目标**：T24 是唯一明确的传送带任务；human 轴 20% 是更大的“移动干扰”来源。两者都用历史/预测，不用基座。
- **头部模型**：MolmoAct2/WALL-OSS-0.5/Spirit-v1.5 的公开瓶颈都在接触/长程；这支持“外挂闭环”而不是“换基座”。

## 5. 风险、合规与 kill criteria

- **残差不是力**：控制器滞后/减速会制造假接触；必须做跨任务校准、多代理投票、 optionally 力标注小数据验证。若 PCO 在 held-out 任务上 AUC < 0.65，降级为“仅用于 SVL 的保守重试”，不进主路径。
- **PRM 可能过拟合步骤标签**：步骤边界是弱分割；用 held-out 任务、反向增广、因果干预（把步骤标签打乱）检验。若 PRM 不能提升 held-out 的撤销检测/成功率，砍掉 RWFM，只保留 SVL。
- **单模型合规**：PCO/PRM 必须是同一 checkpoint 的头；SSG/PGL/SVL 是确定性代码；检索库是数据。模型卡里逐项披露。
- **外部数据**：手册公开部分只到 2.2，外部数据/仿真/预训练权重政策未确认；L2L 默认只做协议，不并入训练；需要邮件确认。
- **延迟**：PCO/PRM 头很轻，但 BoN N=4 会放大基座推理；用 chunk 缓存/批处理，目标 p99 < 100ms（头部分），基座按 chunk 异步。若 180s 内无法完成，N 降到 2。
- **许可**：WLA-1.0-Base 是 Apache-2.0；GR00T N1.5 模型卡是非商用；MolmoAct2/WALL-OSS-0.5 需逐个核对；不能把许可风险带进提交。
- **榜单**：所有榜单数字只作预览；不再用 step-gap 推断失败分布；真实榜单发布后重跑审计。
- **移动基座**：明确不做；如果未来规则/数据出现 base 动作，再另开一轮。
- **步骤分**：只做同分决胜，不为步骤分牺牲成功率；RWFM 的 reward 以 success/progress 为主，步骤权重只是 shaping。
- **第 6 轮教训**：FLEET 被评 6.0，说明“把部署形态当研究轴”不够；本轮只保留工程检查单，研究火力集中在接触/撤销/奖励。

## 6. 一句话押注

**本轮最值得押注的是 CARE-VLA：在强基座上用“残差接触代理（PCO/RFP）+ 评分步骤过程奖励（PRM-S）+ 时序记忆（MTT）+ 接触门控的 best-of-N/恢复”做最后一公里闭环；它同时对上 UniBot 的无力和觉、成功率优先、human 撤销与 T24 移动目标，而不需要新基座或移动基座。**

## 1. 事实核对与纠错

### 1.1 榜单审计：步骤分不是独立测量

对 `leaderboard_data.json` 的 8 个模型分别做 [S4][S5][S6][S7] `step_score ~ success_rate` 的线性回归（每个模型 32 个任务点）：

| 模型 | 成功率 | 步骤分 | k | 截距 b | R² |
|---|---:|---:|---:|---:|---:|
| MolmoAct2 | 29.7 | 39.0 | 1.3133 | −0.0032 | 0.99999963 |
| WALL-OSS-0.5 | 28.5 | 38.9 | 1.3649 | −0.0011 | 0.99999983 |
| DreamZero | 27.9 | 37.9 | 1.3584 | +0.0003 | 0.99999992 |
| Spirit-v1.5 | 25.9 | 34.4 | 1.3283 | −0.0033 | 0.99999993 |
| DM0 | 23.5 | 31.7 | 1.3491 | −0.0042 | 0.99999991 |
| PI-0.5 | 22.8 | 30.6 | 1.3420 | +0.0025 | 0.99999989 |
| GigaBrain-0 | 22.6 | 29.5 | 1.3053 | −0.0012 | 0.99999987 |
| GR00T N1.5 | 20.5 | 28.1 | 1.3707 | +0.0002 | 0.99999989 |

结论：

- 每个模型内部，步骤分几乎是成功率的**确定性线性缩放**；截距接近 0。这不是“两个指标相关”，而是生成脚本的产物。
- 榜单 raw HTML 仍写「即将发布 Coming Soon」；详情页视频全部是「测试视频占位，后续可替换为真实视频文件」；JSON 的 `generated_from` 仍是 `gen_leaderboard.py`。三者互相印证：**当前榜单是预发布/演示，不是真实评测结果。**
- 因此不能用榜单做：排名判断、模型强弱判断、步骤级失败分布推断、轴级瓶颈推断。唯一可谨慎使用的是“难度先验”（例如榜首约 30% 成功率可能接近真实难度），但必须标“未核实”。
- 上一轮“步骤分−成功率≈+8.6pp”的算术是 `(k−1)×success`；它不说明失败在最后一步。**该推论作废。**

### 1.2 官方规则：成功率优先，步骤分只做同分决胜

中文手册原文要点 [S2][S3]：

- 32 个任务、每个任务 10 次独立运行；5 类泛化（位置/干扰物/背景/未见物品/人为干扰）各 2 次。
- 单次真机执行最大 **180s**，超时记为失败，并根据执行情况计算步骤分。
- 仅设通才模型赛道：**同一模型完成全部 32 任务，不得混合多个模型**；模型类型不限（World Model、VLA 均可）。
- 有不计分的单任务测试通道；不计入排行榜。
- **实时榜单按 32 任务总平均成功率排序；成功率相同按总平均步骤分排序；仍相同则提交日期较早者靠前。**
- 官方提供 32 任务全部真机数据；多台机器人、多样化场景/泛化/人为干扰。

对方案的约束：

1. 第一目标是成功率；步骤分只在同分时有用。**不要为了步骤分牺牲成功率。**
2. 终局步骤是成功闸门（32/32 任务），但“失败主要发生在终局”仍需真机验证；不能从合成榜单推断。
3. 单模型规则要求接触/进度/撤销头必须与基座同一个 checkpoint；不能外挂独立 PRM/verifier 模型。
4. 180s 预算允许有限次重试；但长程任务（T16/T17/T31）要限制重试次数。
5. 评测有 5 个轴，每轴 2/10；人为干扰轴占 20%，是“撤销/移动目标”的主要来源。

### 1.5 数据与接口

**数据规模**：HF collection `unibot-v1-challenge-dataset` [S8] 有 32 个数据集；官方任务页写 32k 演示、169h；HangCup [S9][S10] 实测 1,043 条 / 194,564 帧 / 30fps，`lastModified=2026-10-14`；PlugCharger [S11][S12][S13] 第一个数据文件 101MB、130,958 行、269 eps（全数据集 episodes 元数据共 1,022 条）。LeRobot v3，`robot_type=unitree_g1`。

**语言**：每个任务的 `meta/tasks.parquet` 里，`task` 字段是 5 条英文复述用 `@` 连接；32×5=160 条。评测很可能在这些复述里采样；SSG 必须覆盖 160 条，并加中文/未见过复述的兜底。

**相机**：数据集 `head_stereo_left/right`、`wrist_left/right`；API `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`。训练时必须做键映射，不能把数据集键名直接当 API 键名。

**观测/动作** [S15][S16]：

- 观测：4×RGB 480×640；双臂关节 7 或 EE 位姿 6（base 系）；夹爪 1；`lower_body` 15；`observation.language` 单字符串。
- 动作：joint 或 ee 互斥；双臂 7 或 6；夹爪 1；`action.pivot` 7；`action_chunk_size`、`obs_delta_indices`、`image_resize` 自定。
- **没有 force/torque/tactile/current**；`action.gripper_controls` 从字段形态看更像遥操作 trigger/squeeze，不是力/触觉。
- 数据集还有 torso 系 EE、waist、`state_torso`、`state_d435`、`recomputed_ee_valid`；API 不暴露，训练时只能用 API 兼容子集。

**动作空间选择**：主路径用 **joint 动作**（与 WLA-1.0-Base 的 G1 预训练更一致）；EE 位姿只作为 PGL/OPT 的目标表征和 SVL 的校验量，不在推理时切换动作空间。若改用 MolmoAct2/WALL-OSS，需重新核对动作空间和 embodiment 适配。

### 1.6 移动基座负面结果 [S10][S11][S12]

- PlugCharger 首个数据文件 130,958 行、269 eps：`action.pivot` **严格恒为** `[0,0,0,0,0.15,0,0.74]`；`action.base_command` **严格恒为** `[0,0,0,0.74]`；`action.lower_body` 与 `observation.state.lower_body` 逐帧相同。
- HangCup `meta/stats.json`：`action.pivot` 均值 `[~0,~0,1.66e-5,0,0.15,0,0.7384]`，std `[2.1e-5,4.6e-7,0.00717,0,2.8e-4,0,0.00639]`；`base_command` 的 vx/vy 近零，angle 跨 episode 有 ±0.8，height 0.65–0.74。角度变化更像不同 episode 的初始朝向，不是演示中的主动转向。
- 结论：**演示没有主动导航/移动基座**；“移动操作”不能按移动基座做。CARE-VLA 不输出 base 速度，不做 pivot 主动控制；只保留 Pivot Stabilizer 的安全保持。

### 1.7 接触代理小试（PlugCharger，仅提出假设）[S11][S12]

方法：取第一个数据文件的 269 个 episode、130,958 帧；双臂 14 维关节，`action[t]` 对齐 `state[t+Δ]`；残差 `r_t=||a_t−s_{t+Δ}||_2`，5 帧滑动平均；holding 定义为任一把夹爪状态 <2。

| 指标 | 数值 | 说明 |
|---|---:|---|
| 最佳 lag | 3 帧 | lag=3 平均绝对误差 0.01544 rad；lag=0 为 0.02347 rad（降约 34%） |
| 后段峰值 | 233/269（86.6%） | 平滑残差最大值落在 episode 最后 30% |
| max/median | 3.17 | 后段残差相对中位数的放大 |
| last20/first20 | 1.50 | 最后 20% 与最初 20% 的残差比 |
| 与 holding 相关 | 0.304 | 残差与“夹爪闭合/持物”弱相关 |

解释与警告：

- 残差在接近-接触-插入的后段变大，和接触事件同步；这支持“本体残差可做接触代理”的假设。
- 但单任务、无 ground-truth force、无跨任务校准；控制器减速/换向、采样延迟、夹爪标定都会制造假残差。它只能作为 PCO 的弱标签/门控，不能当力传感器。
- 必须补 T10/T26/T19/T23 的跨任务校准，并用“有/无接触”的外部标注或少量力标注小数据做验证。

## 2. 目标函数与任务分类

### 2.1 排名目标

设任务 `i=1..32`，试验 `j=1..10`，`Y_ij=1` 表示 180s 内完成全部步骤。主目标：

```text
S = (1/32) Σ_i (1/10) Σ_j Y_ij
```

步骤分（仅同分决胜）：

```text
G = (1/32) Σ_i (1/10) Σ_j Σ_s w_{i,s} · 1[step s complete]
```

排名：先 `S`，再 `G`，再提交日期。含义：

- 每个任务等权；每个任务 10 次试验等权；5 个泛化轴各 20%。
- 接触关键任务 14/32，占 43.75% 的任务权重；放置/堆叠 18/32，占 56.25%。两条线都必须做。
- 人为干扰轴 20%，且撤销剧本集中在其中；这是 PRM-S/NRB 的主要杠杆。
- 步骤分只在成功率打平时有用；不要把步骤分当主目标。

统计功效（重要修正）：

- 320 次试验，`p≈0.3` 时 `SE=sqrt(0.3×0.7/320)=2.56pp`；95% CI 约 ±5.0pp。
- 相对固定基线 `p0=0.3` 的单比例双侧检验，`+3pp` 的功率约 **21%**；`+5pp` 约 **50%**；`+7pp` 约 **78%**；`+7.5pp` 约 **86%**。
- 因此不能把一次官方跑的 +3pp 当结论；要用任务级配对 bootstrap、机制指标（PCO/PRM AUC、恢复率）、以及多个调试槽。此前“+3pp 约 80% 功率”的说法不严谨，本报告修正。

### 2.2 为什么是接触/撤销/验证

1. **成功要求所有步骤完成**：终局是 32/32 的闸门；但合成榜单不能告诉我们失败分布。接触/放置的最后一公里是结构上的高风险段，必须做闭环验证。
2. **接触关键任务占 14/32**：插入、闭合、拉链、锁合、倾倒、注射；这些任务的失败往往是“看起来做完、实际没到位”。
3. **撤销是 human 轴的结构性难点**：T27“叠了第二个之后拿下第二个”、T19“拉上拉链之后拉开”、T14“拧开盖子之后拧动回来”、T17“笔盒合上之后手动打开”、T16“叠完毛巾翻开”。只向前走的策略会被撤销打回原形。
4. **基座强在语义/空间，弱在接触/时序/恢复**：公开模型的瓶颈描述支持“外挂闭环”而不是“换更大基座”。
5. **无真实力觉**：残差/夹爪/视觉代理是唯一可行路径；这也形成差异化。

### 2.3 设计原则

1. **单 checkpoint**：PCO/PRM/MTT 都是基座特征上的头；不跑第二个模型。
2. **成功率优先**：过程奖励只做 chunk 选择、恢复触发、RWFM 加权；不替代成功判定。
3. **代理不冒充传感器**：所有接触信号写“proxy”；模型卡披露无 force/tactile。
4. **历史条件化**：至少 4–8 帧历史；撤销/移动目标本质是时序问题。
5. **确定性优先**：SSG/PGL/SVL/Pivot Stabilizer 用确定性代码；学习只用在感知/评分。
6. **延迟预算**：头 <10ms；BoN N≤4；基座按 chunk 异步；180s 内完成。
7. **可证伪**：每个组件有离线/仿真/真机门槛和 kill criteria。

```text
     p_contact/f_proxy        p(step)/progress/reversal   relative motion
          └────────────────────────┼────────────────────────┘
                                   ▼
   BoN: sample N chunks; score p_success + α·progress − λ·f_proxy − μ·p_reversal
                                   ▼
   SVL: servo→slow place/insert→settle/verify→NRB retry/regrasp/relocate
                                   ▼
   Pivot Stabilizer: pivot=[0,0,0,0,0.15,0,0.74]; base=[0,0,0,0.74]; never zero height
```

### 3.3 SSG：评分步骤图（保留）

- 输入：`observation.language`；输出：任务 ID、步骤序列、当前步骤 `s`、权重 `w_s`、终局谓词。
- 覆盖 32×5=160 条英文复述；中文描述做兜底；未见复述用关键词/句向量 + 任务先验。
- 与 PRM-S 互补：SSG 是“规则骨架”，PRM-S 是“数据驱动的进度/撤销估计”；两者不一致时，以视觉/本体校验为准，不盲目信语言。
- 保留第 7 轮的表 A/B；本轮只加“撤销边”：每个步骤允许 `s→s-1` 的回退，NRB 用。

### 3.4 PGL / OPT / ICR（保留，接触感知升级）

- **PGL**：槽位/区域→2D 锚点→6D 位姿；锚点来自演示目标 + 检测/分割；透明/反光物体用多视角/腕部近景兜底。
- **OPT**：K 条演示的“容器系释放位姿”中位数 + 离散度；离散度大→更保守的伺服/缓放；离散度小→直接放置。接触任务（插头/网线/拉链）把“插入位姿”也纳入，不只释放位姿。
- **ICR**：关系中心键（物体-容器相对位姿 + 相位 + 夹爪状态），不是全局外观；缓存编码控延迟；透明/布料任务回退到“相位检索 + 动作先验”。

### 3.5 PCO/RFP：本体感受接触观察器 + 残差力代理（新增，押注）

**目标** [S34][S35][S36]：在没有力/触觉的 API 下，估计“是否接触、处于哪个接触相位、受阻多大、是否滑移/未到位”。

**输入**：

- 最近 K 帧双臂关节/EE、夹爪指令与状态；
- 动作 chunk；
- 腕部 RGB（近景）；
- SSG 当前步骤/阶段（接近/接触/插入/保持/释放）。

**输出**：

- `p_contact`：接触概率；
- `phase`：5 类（free/approach/contact/insert/hold/release，可合并）；
- `f_proxy`：受阻标量（归一化，不是牛顿）；
- `p_slip` / `p_misaligned`：滑移/未对准概率。

**特征**：

```text
r_t = || a_t^{arm} − s_{t+Δ}^{arm} ||_2          # Δ=3，按任务校准
z_t = (moving_average(r_t, 5) − μ_task) / σ_task
g_t = |a_gripper − s_gripper| / g_scale          # 闭合阶段
v_t = wrist_contact_head(o_t^{wrist})             # 弱视觉接触
x_t = [z_t, g_t, v_t, ee_error_t, joint_velocity_t, step_embedding_t]
```

**在线可用性（关键）**：离线 `lag=3` 只是标签对齐；在线不能偷看 `s_{t+3}`。PCO 在时刻 `t` 只能用：已实现的 `a_{t-3}` 与 `s_t` 的延迟残差、`a_t` 与 `s_{t+1}` 的一步跟踪误差、夹爪命令-状态差、腕部视觉。BoN 评分用上一 chunk 的已实现残差 + 当前观测；新 chunk 的残差要执行后才知道，不能用于同一时刻的选择。

**训练标签**（弱监督）：

- 正样本：`z_t > τ_z` 且（`g_t > τ_g` 或 `v_t > τ_v`）；
- 负样本：三者都低；
- 排除换向/减速的过渡帧；
- 可选：少量力标注数据做蒸馏/校准（默认关闭，等政策）。

**损失**：

```text
L_PCO = BCE(p_contact, y_contact)
      + CE(phase, y_phase)
      + λ_s SmoothL1(f_proxy, y_proxy)     # y_proxy 为归一化残差/弱标签
      + λ_t temporal_consistency
```

**使用**：

- 接触门控：`p_contact` 高时降低末端速度/步长，增加 SVL 校验；`p_contact` 低时不要过早判定“插入成功”。
- 受阻：`f_proxy` 高且 `progress` 不增→回退/重对准；`f_proxy` 突然下降→可能滑脱/拔出→重抓。
- BoN：把 `f_proxy` 作为惩罚项，优先选择“接触后仍能推进”的 chunk。
- **不声称测力**：模型卡写“proprioceptive contact proxy, no force/tactile sensor”。

### 3.6 PRM-S：评分步骤过程奖励（新增，押注）

**目标** [S40][S41][S42][S43]：把官方 `score_steps` 变成可打分的中间信号，用于 chunk 选择、撤销检测、恢复触发、RWFM 加权。

**输入**：基座隐藏特征 `h_t`（或小的历史 transformer）+ SSG 步骤嵌入 + PCO 输出 + 动作 chunk 摘要。

**输出**：

- `p_step`：步骤索引（softmax，最大 5）；
- `progress`：步骤内进度 [0,1]；
- `p_reversal`：撤销/回退概率；
- `p_success`：最终成功概率；
- `v_progress`：价值（可选）。

**损失**：

```text
L_PRM = CE(p_step, y_step)
      + λ1 MSE(progress, y_progress)
      + λ2 BCE(p_reversal, y_reversal)
      + λ3 BCE(p_success, y_success)
      + λ4 ranking_loss(chunk_good, chunk_bad)
```

**标签**：

- 步骤：官方 `score_steps` + 动作/夹爪/视觉变化点弱分割 + 人工抽检；
- 进度：步骤内时间/关键点/视觉完成度；
- 撤销：human 备注 + 反向动作 + 仿真回放；
- 成功：episode 最终是否全步骤完成；
- chunk 偏好：同一状态下，能推进步骤/避免撤销的 chunk 为正。

**使用**：

- BoN：`score = p_success + α·progress − β·p_reversal − γ·f_proxy`；
- RWFM：`w = clip(exp(β·(p_success + α·progress − μ·p_reversal)), w_min, w_max)`；
- 恢复：`p_reversal` 超阈值→NRB 重做当前/上一步；
- SSG 校验：`p_step` 与规则步骤不一致→以视觉/本体为准，触发检查。
- **单模型**：PRM-S 是基座特征上的小头；不单独跑第二个模型。

### 3.7 MTT：移动目标/干扰的时序记忆（新增）

- 输入：最近 K 帧 RGB/本体/动作；输出：目标相对位置/速度、拦截点、干扰位移。
- T24：估计传送带速度与食物到达时间，选择“未来时刻”的抓取点；不追当前帧。
- human 轴：检测目标被平移/拿走/撤销；触发重定位/重抓。
- 实现：轻量时序 transformer/GRU + 相对位姿；不引入 14B 视频模型；与 PRM-S 共享历史特征。
- 训练：从演示中做“未来帧预测/相对运动”自监督；human 备注做事件标签；仿真做反事实。

### 3.8 SVL / NRB：落点/插入验证与恢复（升级）

**SVL**：

1. 伺服到目标附近；
2. 接触门控：`p_contact` 高→减速/小步；`p_contact` 低→继续接近；
3. 插入/放置：监控 `f_proxy`、EE 误差、视觉到位；
4. settle：等待 0.3–0.5s，比较物体位姿/接触；
5. 判定：成功→下一步；失败→NRB。
- 对拉链/闭合：验证最终闭合状态；对堆叠：验证上层稳定；对插头/网线：验证插入深度/卡扣。

**NRB**：

- 撤销：`p_reversal` 高→重做当前/上一步；
- 未到位：`f_proxy` 高但 `progress` 不增→回退/重对准；
- 滑脱：`f_proxy` 突降 + 物体位移→重抓；
- 重试预算：每任务 ≤2 次；长程任务 ≤1 次；180s 内。

### 3.9 BoN：chunk 选择（新增）

- 从基座采样 N 个 chunk（N=2–4）；
- 用 PRM-S/PCO 打分：`p_success + α·progress − β·p_reversal − γ·f_proxy + η·consistency`；
- 选最高分，执行前 `H_exec` 步，重新观测/重规划；
- 延迟控制：批处理、缓存、N=2 兜底；若 p99 超预算，退回 N=1 + SVL。
- 与 SVL 的关系：BoN 选“看起来更好”的 chunk；SVL 负责“执行后验证”。两者不互相替代。

### 3.10 Pivot Stabilizer（工程保护，新增）

- `action.pivot = [0,0,0,0,0.15,0,0.74]`；`action.base_command = [0,0,0,0.74]`；
- 绝不输出零 pivot（零 height 会危险）；裁剪到数据集安全范围；
- 如果 API 对 pivot/base 有归一化/单位差异，先用调试槽核对，再上线；
- 不把 pivot 当动作自由度；不做 base policy。

### 3.11 单 checkpoint 合规

- PCO/PRM/MTT 都是基座特征上的头，随基座一起保存/加载；提交的“模型”是一个 checkpoint。
- SSG/PGL/SVL/Pivot Stabilizer 是确定性代码；ICR/NRB 是数据/检索库，不是第二个学习模型。
- 模型卡逐项披露：辅助头、检索库、确定性模块、无 force/tactile、外部数据（默认无）。
- 若官方审计认为“辅助头”也算多模型（可能性低），退路：把 PCO/PRM 蒸馏进基座 token/动作专家，仍是一个 checkpoint。

## 4. 数据引擎

### 4.1 步骤标签

- 解析 32 个 `info.json` 的 `score_steps`，得到步骤文本/权重/顺序。
- 帧级步骤边界官方未给；用弱分割：
  - 夹爪开合、EE 速度/加速度突变；
  - 物体/容器相对位姿变化；
  - 语言子目标关键词；
  - 视觉接触/遮挡变化。
- 人工抽检：每任务 2–5 条，共 64–160 条；标注步骤边界/失败点；用于校准弱分割。
- 对重复步骤（T02/T04/T13/T15/T20/T21/T25 等）：用物体顺序/颜色/位置消歧；不能只按时间等分。
- 产出：`(episode, t, step, progress, reversal, success)` 标签集；训练/验证按任务划分，避免泄漏。

### 4.2 弱接触标签

- 正样本：`z_t > τ_z` 且（`g_t > τ_g` 或 `v_t > τ_v`）；
- 负样本：三者都低；
- 过渡帧：换向/减速/快速运动，排除或降权；
- 跨任务校准：每个任务用自己的 `μ_task, σ_task`；避免长任务残差天然更大。
- 验证：held-out 任务 AUC、与人工接触标注的一致性；若 <0.65，PCO 只做 SVL 保守重试，不进 BoN。

### 4.3 撤销增广

- 来源 1：human 备注（T27/T19/T14/T17/T16 等）→ 事件标签/场景脚本；
- 来源 2：成功 episode 的反向动作段→合成撤销；物理不精确，低权重（0.1–0.3）；
- 来源 3：仿真中显式撤销（拉开拉链、拿走碗、拧回瓶盖）；
- 标签：`p_reversal=1` 的区间 + 恢复目标步骤；
- 风险：反向动作可能产生非物理状态；只用于“检测/恢复”头，不用它训练基座动作。

### 4.4 语言

- 32×5=160 条英文复述；训练时随机采样；SSG 覆盖全部。
- 中文描述做辅助；未见复述用句向量/关键词兜底。
- 不要把语言当唯一阶段信号：语言是 episode 级常量，步骤进度主要靠视觉/本体。

### 4.5 数据集/API 映射

| 数据集 | API | 处理 |
|---|---|---|
| `head_stereo_left/right` | `cam_left_high/cam_right_high` | 键映射；分辨率缩放 |
| `wrist_left/right` | `cam_left_wrist/cam_right_wrist` | 键映射；近景保留 |
| `left/right_ee_pose_gripper_base` | 同名 base 系 | 直接用 |
| `left/right_ee_pose_gripper_torso` | 不暴露 | 不用于 API 兼容训练 |
| `waist_state_joint`、`state_torso`、`state_d435` | 不暴露 | 可做辅助监督，推理不用 |
| `action.left/right_arm` 7 | joint 动作 | 主路径 |
| `action.left/right_gripper` 1 | 夹爪 | 主路径 |
| `action.pivot` 7、`action.base_command` 4 | pivot/base | 固定名义值；Pivot Stabilizer |
| `action.lower_body` 15 | lower_body | 固定/不主动控制 |
| `action.gripper_controls` | 不暴露 | 只做遥操作分析，不当力 |

### 4.6 可选：带力标注的实验室数据

- 若合作实验室有 G1/力传感器，采 500–1,000 条接触关键轨迹（T10/T26/T19/T23/T31），做 FD-VLA 式蒸馏/校准 [S35]。
- 默认关闭：手册只读到 2.2，外部数据政策未确认；先邮件 `challenge_support@unitree.com`。
- 若允许：PCO 的 `f_proxy` 用真实力做校准，但不改变“推理无 force”的事实；模型卡披露。

### 4.7 规模与算力

- 32 任务、约 33k episodes、169h；base 微调用全部任务，PCO/PRM 用接触关键 + 撤销/放置平衡采样。
- 训练：8×H100/A100 级别；WLA-6B 全参/LoRA 视资源；头训练单卡即可。
- 推理：基座 chunk 异步；头 <10ms；BoN N≤4；目标 p99 在 chunk 预算内。

## 5. 训练配方

### 5.1 阶段

| 阶段 | 内容 | 数据 | 冻结 | 目标 |
|---|---|---|---|---|
| 0 | 基座继续预训练/微调 | 32 任务全部 | 头未接 | 动作 chunk 的 BC/flow matching |
| 1 | 接 PCO/PRM/MTT 头 | 步骤/接触/撤销标签 | 基座可选冻结 | 头收敛；不破坏基座 |
| 2 | RWFM/BoN 微调 | chunk 偏好/成功 | 基座低 LR | 提升成功/恢复，不回归 |
| 3 | 校准/压缩 | 调试槽数据 | 全冻 | 阈值/延迟/安全 |

### 5.2 损失

```text
L = L_action
  + λ_pco L_PCO
  + λ_prm L_PRM
  + λ_mtt L_MTT
  + λ_rw L_RWFM
  + λ_reg ||θ−θ0||²
```

- `L_action`：基座原有 flow matching/BC；joint 动作。
- `L_PCO`：接触/相位/受阻/滑移弱监督。
- `L_PRM`：步骤/进度/撤销/成功/排序。
- `L_MTT`：相对运动/未来目标预测。
- `L_RWFM`：`w·||v_θ(a_t,t)−(a−ε)||²`，权重由 PRM/PCO 给；clip 防爆。
- `L_reg`：防头训练破坏基座。

### 5.3 超参（起点，需调）

| 项 | 值 |
|---|---|
| 历史 K | 4–8 帧（30fps，约 0.13–0.27s） |
| action horizon | 16–30（WLA 原生 30） |
| BoN N | 2–4 |
| 执行步数 H_exec | 4–8 |
| 接触阈值 τ_z | 按任务校准；初值 1.0–1.5σ |
| RWFM β | 0.5–2.0；clip [0.2, 5] |
| 撤销增广权重 | 0.1–0.3 |
| 重试预算 | ≤2/任务；长程 ≤1 |
| 学习率 | 基座 1e-5–5e-5；头 1e-4–3e-4 |

### 5.4 算力与时间

- 8×H100 约 3–5 天完成基座微调（视参数高效方案）；头训练 1–2 天。
- 若只有 4×A100：LoRA/冻结视觉塔，优先接触关键任务；全量 32 任务用低分辨率/短历史。
- 推理：WLA-6B 在单张 A100/L40S 上按 chunk 异步；BoN 可能成为瓶颈，先 N=2。

### 5.5 课程/采样

1. 先静态放置/抓取（T01–T04 等）稳基座；
2. 加接触关键（T10/T26/T19/T23/T31）；
3. 加撤销/干扰（human 剧本、合成撤销）；
4. 加 T24 移动目标；
5. 最后全任务混合，防遗忘。

### 5.6 评测门

- 离线：步骤准确率、撤销 AUC、接触 AUC、progress MAE；
- 仿真：4 任务成功率、恢复率、延迟；
- 调试槽：2 个任务 A/B；
- 官方：全任务成功率/步骤分；
- 每级有 kill criteria（§7.7）。

```text
obs_delta_indices = {

  state.lower_body: [0],               # 固定
}
image_resize = 320×240 或 384×288（按基座）
action_chunk_size = 16–30
```

- 历史用于 MTT/PRM-S；不改变基座输入接口。
- 图像缩放/锚点渲染在 `image_resize`/预处理里做；不引入额外模型。

### 6.2 控制循环

```text
for each episode:
  reset(); obs = get_obs()
  s = SSG(language)
  for t in 0..T:
    z = encode(obs, history, s)
    chunks = base.sample(z, N)                  # N=2–4
    scores = PRM_S(z, chunks) + PCO(z, chunks)
    a = argmax(scores)
    execute(a[:H_exec])
    obs = get_obs()
    s, rev = update_step(s, obs, PRM_S, SVL)
    if rev: a = NRB(s, obs)
    if SVL.fail: a = NRB(s, obs)
    if timeout: break
```

### 6.3 接触门控

- `p_contact < τ_low`：正常接近；不要判定插入成功。
- `p_contact` 中：减速/小步；增加腕部近景权重。
- `p_contact` 高且 `f_proxy` 高、`progress` 不增：回退 2–5mm/重新对准；不要硬顶。
- `p_contact` 高且 `f_proxy` 突降：可能滑脱/拔出；重抓。
- 所有阈值按任务校准；透明/反光物体用视觉+EE 残差投票。

### 6.4 撤销恢复

- `p_reversal > τ_rev`：NRB 重做当前/上一步；
- 若撤销来自人（目标被拿走/移动）：MTT 重定位；不要重复原轨迹；
- 若撤销是“拉链被拉开/碗被拿下”：重新执行闭合/堆叠；
- 恢复动作也要过 PRM-S/PCO，避免二次失败。

### 6.5 时间预算

- 180s/任务；演示中位数约 6–10s；长程 20–30s；
- 接触重试 1–3s/次；BoN 额外 0.2–1s/chunk（视基座）；
- 预算：每任务重试 ≤2；长程 ≤1；若剩余 <20s，关闭 BoN，只做 SVL 保守重试。

### 6.6 失败处理

- 检测不到目标/锚点：回退到任务先验位置；请求重定位；
- 连续两次接触失败：改变接近方向/高度；不要重复同一轨迹；
- 视觉被遮挡：用 EE/本体残差；降低速度；
- 超时前：优先完成当前步骤，不开启新步骤。

### 8.2 新增项展开

#### I14 PCO/RFP：无传感器接触代理

- **动机**：API 无 force/tactile；接触关键任务 14/32；插入/闭合失败常因“没到位”。
- **差异**：不是“预测力”，而是“从本体残差/夹爪 stall/腕部视觉估计接触概率与受阻”；不依赖力硬件。
- **可行性**：数据现成；PlugCharger 小试有信号；头轻量。
- **资源**：1 人 2 周；单卡训练；跨任务校准需 4 任务数据。
- **步骤**：残差/夹爪/视觉特征→弱标签→头训练→跨任务 AUC→SVL 门控→BoN 评分。
- **风险**：控制器滞后混淆；透明/反光物体视觉弱；跨任务漂移。
- **状态**：押注，P0；kill：跨任务 AUC<0.65。

#### I15 PRM-S：评分步骤过程奖励

- **动机**：官方 `score_steps` 是稠密步骤信号；撤销需要时序判断；单模型不能外挂 PRM。
- **差异**：步骤/进度/撤销/成功四头一体；history-conditioned；与 SSG 互补；只做选择/恢复，不替代成功率。
- **可行性**：步骤标签可从官方 JSON + 弱分割得到；撤销可从 human 备注/反向动作增广。
- **资源**：1 人 3 周；头训练 1–2 天；标注抽检 1 周。
- **步骤**：步骤分割→标签→头训练→撤销 AUROC→BoN/RWFM→调试槽。
- **风险**：弱分割噪声；撤销增广非物理；过拟合步骤标签。
- **状态**：押注，P0；kill：撤销 AUROC<0.75。

#### I16 RWFM：奖励加权 flow matching

- **动机**：把 PRM/PCO 的信号变成训练权重，提升好 chunk 概率；比纯 BoN 更省推理。
- **差异**：权重来自“成功+进度−撤销−受阻”，不是人工 reward；clip 防爆；小权重起步。
- **可行性**：基座是 flow matching；改损失即可；风险是分布偏移。
- **资源**：1 人 1–2 周；需稳定训练。
- **步骤**：离线 chunk 偏好→权重→微调→回归测试→与 BoN 二选一/并用。
- **风险**：reward hacking；正常任务回归；权重不稳。
- **状态**：P1；kill：正常任务回归>2pp。

#### I17 MTT：移动目标/干扰

- **动机**：T24 传送带；human 轴 20%；单帧模型无时序。
- **差异**：不做视频世界模型；用短历史+相对运动+拦截点；与 PRM 共享特征。
- **可行性**：`obs_delta_indices` 支持历史；数据有 T24；实现轻。
- **资源**：1 人 2 周；T24 数据/仿真。
- **步骤**：历史编码→相对运动→T24 拦截→human 干扰检测→调试槽。
- **风险**：T24 只有 1/32；human 干扰随机；过拟合。
- **状态**：P1；kill：无增益。

#### I18 BoN：chunk 选择

- **动机**：基座单次采样可能选到“看起来对、接触失败”的 chunk；PRM/PCO 可打分。
- **差异**：用同 checkpoint 的头打分，不引入外部 verifier；N 小、延迟可控。
- **可行性**：基座支持 chunk 采样；头轻；批处理。
- **资源**：1 人 1 周；推理优化 1 周。
- **步骤**：采样→打分→执行→延迟测试→N 自适应。
- **风险**：延迟；打分与真实成功不一致；模式坍缩。
- **状态**：P1；kill：p99 超预算 2×。

#### I19 Pivot Stabilizer：固定基座安全

- **动机**：数据 pivot/base 恒定；零 pivot 会命令 height=0；移动基座不考。
- **差异**：把“不动作”做成显式保护；防止模型学到错误的 base 动作。
- **可行性**：确定性代码；一行默认值。
- **资源**：0.5 人日；调试槽核对。
- **步骤**：默认值→裁剪→日志→上线检查。
- **风险**：API 单位/归一化差异；不同任务 height 略有差异。
- **状态**：P0 工程；必须做。

#### I20 榜单审计：防止合成数据误导

- **动机**：step=k×success；视频占位；Coming Soon。
- **差异**：把“数据可信度”当研究前置条件；所有结论标注来源等级。
- **可行性**：已完成；脚本可复用。
- **资源**：0.5 人日。
- **步骤**：JSON 回归→页面证据→来源表→真实榜单发布后重跑。
- **风险**：官方可能更新数据；需定期复核。
- **状态**：完成；P0 研究卫生。

### 8.3 已砍/降级清单

- **移动基座/pivot 主动控制**：数据无主动移动；评测不考；砍。
- **FLEET 第六轴**：部署是工程，不是研究主轴；降级检查单。
- **独立 PRM/verifier 模型**：单模型规则；砍，改头。
- **14B DreamZero/WAM 主路径**：太重；只借 latent verifier 思路。
- **“失败集中在最后一步”**：合成榜单不能证明；改为假设。
- **“步骤分是主目标”**：排名成功率优先；改为同分决胜/训练信号。
- **全 32 任务高保真孪生**：成本高；只做 4 任务校准。
- **默认外部实验室数据**：政策未定；默认关闭。
- **每任务 LoRA/多模型**：单模型规则；砍。

## 12. 开放问题

1. 外部数据（自采/实验室/仿真/预训练权重）是否允许？手册公开部分只到 2.2；需邮件确认。
