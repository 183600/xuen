## 一、上一轮留下的四个口子

v7.2 QUC 把「单列删除 → 强制 $s_i=t$」做成了根层扫描，用支持引理把候选压到当前 LP 解的 support，7/201 根分数实例在 2 次探针内闭合。复盘时我记下四个具体口子：

1. **探针对象太原子**：删的是单列 $(i,t)$。support 引理明明说「所有可认证的单点都在 support 里」，那把**整组 support 一起删**会得到什么？
2. **$|E|>1$ 的 quorum 没有被处理**：v7.1 的叶子 quorum 可以是多列，v7.2 的单列规则只是 $|E|=1$ 的特例。多列 quorum 能不能主动探测？
3. **force 之后就算了**：QUC 要么陷阱判 NO，要么把 forced 单元写进 force 回退 QNC。「写进 force 再重解、再探针」这条递归路径没有实现。
4. **跨任务路径从未被压过**：201 例里 cross 0 命中，审计的正确性从没被真正测试。

## 二、灵感词与第一反应

本轮的灵感词是 **problem transformation / recursion / 解空间树**。

- **problem transformation**：不要问「这一列能不能删」，而问「把任务 $i$ 当前的整个 support $S_i(z)$ 删掉，LP 还能不能活」。问题的对象从**列**变成**集合**；不可行时，对偶证书的 essential scope $E$ 就是变换的产物——一个可能多列的 quorum。
- **recursion**：拿到 force 不是终点。把 $E_i$ 写进任务域，**重解 LP，再探针**，直到不可行（叶子）或没有新 force。这正是上一轮「下一步」里写的内部探针 + 多列 quorum 的合并版。
- **解空间树**：树的角色下降为兜底。主循环变成「LP 解 → support → 探针 → force → 重解」；只有闭合失败才做中位数分支。

## 三、problem transformation：support 删除探测

设 $\mathrm{LP}(C,S_i(z))$ 是把任务 $i$ 在当前解里的所有正分量列删掉后的 LP。若它不可行，取 Farkas 证书的 **essential scope** $E\subseteq S_i(z)$（由 $b^Ty=-1$ 归一化的整数对偶做负 slack 重放得到），则

$$\mathrm{LP}(C,E)\ \text{不可行},\qquad E\subseteq S_i(z).$$

于是任何可行调度的指标向量必须在 $E$ 里取一个 1：

$$\bigvee_{(j,t)\in E}(s_j=t).$$

这是全局有效子句，不是节点局部结论。当 $E$ 只落在一个任务 $i$ 上时，就得到**域 force**：

$$s_i\in E_i.$$

方向仍然是 force 不是 ban：$E$ 是**被删的列**，结论是「必须落在 $E_i$」。$E_i$ 可以是一个区间、两个离散点，或者恰好等于原域。

## 四、strict 多列 quorum：真的出现吗

$|E_i|\ge 2$ 的 force 比单点强，但只有在「每个单列探针都不可行」时才是**严格**更强。我定了一个可执行判据：

> 在同一节点、同一割集下，若每个 $t\in E_i$ 的 $\mathrm{LP}(C,\{(i,t)\})$ 都可行，而 $\mathrm{LP}(C,E_i)$ 不可行，则这个 set force 严格强于任何单列探针。

我在 sets-first 顺序下埋了 replay，对每个多点 force 回放单点可行性。结果：**7 个严格事件**——holdout47 job6 $\{2,8\}$、stress2/27/49 job6 $\{2,8\}$、stress5/31/42 job14 $\{2,3\}$，其中 stress49 发生在 depth=1。也就是说，多列 quorum 不是纸上定理，它在真实实例上出现，而且单列探针永远拿不到它。

## 五、最大的负结果：严格 ≠ 划算

如果让 set 探针优先（`sets_first`），252 例变成 **777 LP / 333 节点**；units-first 是 594/269。只开 set 探针（`nounit`）更差：**837 LP / 321 节点**。多点 force 事件从 1 个涨到 26/34 个，可是每次 set 探针要删一整个 support、解一次 LP，命中的收益抵不过探针成本。

结论：**set 探针是一个有效但不该优先的算子**。最优 portfolio 是单列探针优先、set 探针兜底。这也解释了 201 主表上 LP 与 QUC 持平——真正的收益来自另一个机制。

## 六、真正的收益：一次探针的 force 闭合

units-first 下，7 个根分数实例每个只需要 **1 次单列探针**：删一个端点不可行 → force → 重解 → 直接不可行 → 用 QNC 的叶子证书闭合。v7.2 需要 2 次探针（两个 forced 单元构成陷阱）。LP 数一样（根 3–4 + 2），但证明形状从「两叶陷阱」变成「force + 叶子」，探针减半。

- 201 例：QNC 268 LP / 213 节点 → QUC 260/191（14 探针、7 陷阱）→ QSP 260/191（**7 探针、0 陷阱**）。
- 新压力集 h5h47（51 例）：QNC 317/202 → QUC 376/95（167 探针，且审计被 cross bug 卡住）→ QSP 317/92（67 探针）。
- 252 例总计：QNC 585/415，QUC 636/286，**QSP 577/283**——第一次在两个轴上同时压过 QNC。
- 内部节点再探（root 4 + internal 1）把节点压到 269，但 LP 回升到 594；depth>0 的 force 只有 1 个。递归的收益在「节点内闭合」，不在「树深」。

## 七、顺手抓到的 v7.2 审计 bug

压力集第 24 例触发跨任务优先序共识：units $(6,15)$ 与 $(8,21)$，$p_6=7$，$21<15+7$。v7.2 `audit_quc` 里写的是

## 0. 版本关系与本轮增量

本轮产物是 **v7.3 QSP-ALC（Quorum Support Portfolio ALC）**，直接建立在 v7.2 QUC-ALC 与 v7.1 QNC-ALC 之上：不改 v6.0 的 SD 割数学，不改 v6.1 的中位数分支规则和 anytime 接口形状，不加新的证明规则，只把「探针对象」和「探针之后的动作」两件事重构：

1. **支持删除探测（problem transformation）**：删除任务 $i$ 在当前 LP 解里的整个 support $S_i(z)$，而不是单个原子 $(i,t)$；
2. **essential scope 提取**：从 $b^Ty=-1$ 归一化的整数对偶做负 slack 重放，得到 quorum 本质域 $E\subseteq S_i(z)$，并验证全局子句 $\mathrm{LP}(C,E)$ 不可行；
3. **单任务 set force**：$E$ 只落在一个任务上时，把全局域缩到 $E_i$（可以是多点集合，严格推广 v7.2 单点 force）；
4. **force 闭合递归（recursion）**：拿到 force 不返回，写入域后重解 LP、再探针，直到 LP 不可行（叶子）或没有新 force；只有闭合失败才回退 v7.1 中位数分支；
5. **动作 portfolio**：单列探针与 set 探针按顺序排列（span-2 单列优先，非 span 任务 set 兜底），命中 trap / cross / conflict 立即终止；顺序只影响探针预算命中率，不影响正确性。

顺带修复一个 v7.2 审计 bug：`audit_quc` 处理优先序 cross 时用 `self.cross[:4]`，而 `cross=('prec',i,t,j,u)`，字段错位导致正确证书被判 `False`；v7.3 的 `audit_qsp` 用 `self.cross[1:5]`。

推荐接口（v7.3 默认配置 = 表中 QSP-2）：

    QSP(inst, h, probe_budget=24, node_budget=2, internal_budget=0,
        portfolio='units_first', unit_probe=True)
    .decide(budget, nodecap, max_rounds, topk) -> (verdict, state)
    .audit_qsp() -> bool

递归变体（表中 QSP-4/1）：`node_budget=4, internal_budget=1`。

与 v7.2 的关系：QUC 的单元探针就是 QSP 的 span-2 单列动作；QUC 的根层陷阱就是 portfolio 的终止条件；QUC 的「扫描失败回退 QNC」被拆成「单列动作之后接 set 动作，再回退 QNC」。v7.3 的新东西不是更强的证明强度，而是：一处更强的**算子**（support 删除）和一处更强的**搜索策略**（force 闭合）。

## 1. 符号

- $n$：任务数；$m$：机器数；$p_i$：加工时间；$\mathrm{pred}(i)$、$\mathrm{succ}(i)$、$\mathrm{elig}(i)$。
- $h$：待判定的 makespan 上界；$T=h$；$\mathrm{est}_i$、$q_i$、$D_i=\{\mathrm{est}_i,\dots,h-q_i-p_i\}$。
- 列 $c$：非资格 $(i,t)$，资格 $(i,k,t)$；$\mathrm{atom}(c)=(c_0,c_{\text{last}})$。
- $C$：已分离的 SD 割集；$\mathrm{LP}(C,E)$：在割集 $C$ 下把原子集 $E$ 的所有列删掉后的 start-time LP。
- $z$：当前节点 $\mathrm{LP}(C)$ 的一个可行解；$S_i(z)=\{t:\sum_c z_c>0,\ \mathrm{atom}(c)=(i,t)\}$。
- $\Phi$：整数 Farkas 证书，$b^Ty=-1$ 归一化；$\mathrm{verify}(\Phi,\mathrm{forbid}=E)$ 逐列重放。
- **本质域** $E$：由 $\Phi$ 的负 slack 列塌缩成的原子集，$E\subseteq S_i(z)$，且 $\mathrm{LP}(C,E)$ 不可行。
- **set force**：$E$ 只含一个任务 $i$ 时记 $E_i=\{t:(i,t)\in E\}$，全局结论 $s_i\in E_i$。
- **force 事件** $(i,E_i,E,\Phi)$：一次把 $E_i$ 写进域的记录，$\Phi$ 是 $E$ 上的有效证书。
- $r$：`node_budget`（根节点最多探针数）；$r'$：`internal_budget`（内部节点最多探针数）；$B_p$：`probe_budget`（整次运行最多探针数）。
- $B$：总 LP 数；$L$：QNC 叶子证书表；$Q$：clause 表；$F^{\mathrm{force}}$：强制域字典。
- `portfolio`：动作序列，元素为 `('unit',i,t)` 或 `('set',i,S_i)`。
- `re_solve`：一次 force 之后回到 LP 求解的闭合迭代。

## 2. 形式定义

### 2.1 支持删除探测

设当前节点割集 $C$、可行解 $z$、任务 $i$。构造 $b_2$：把 $S_i(z)$ 中所有正分量列置零（资格感知时是 $(i,k,t)$ 全部机器列）。解

$$\mathrm{LP}(C,S_i(z)).$$

若可行，返回空（不产生任何结论）；若不可行，提取整数 Farkas 证书 $\Phi$（$b^Ty=-1$），并取

$$E\ :=\ \{\mathrm{atom}(c)\ :\ c\ \text{被删},\ s_c=(A^Ty)_c<0\},\qquad E\subseteq S_i(z).$$

一次探测的成本：1 次原始 LP（删除列）+ 1 次整数对偶提取 LP。

### 2.2 quorum 引理

若 $\mathrm{LP}(C,S_i(z))$ 不可行，且 $E$ 按 2.1 提取，则 $\mathrm{LP}(C,E)$ 不可行，且每个可行整数调度都满足

$$\bigvee_{(j,t)\in E}(s_j=t).$$

特别地，$E$ 是**全局有效子句**，与 $z$ 的选择、与当前节点边界无关（只依赖 $C$，而 $C$ 中每条割都是整数调度有效不等式）。

### 2.3 单任务 set force

若 2.2 的 $E$ 满足 $\{j:(j,t)\in E\}=\{i\}$，则

$$\text{每个可行调度都有 } s_i\in E_i.$$

与 v7.2 单点 force 的关系：$|E_i|=1$ 时退化为 $s_i=t$；$|E_i|\ge2$ 是新的多点域 force。同一任务两个 force 的允许集交集为空时，得到冲突（空域），直接 NO。

### 2.4 force 闭合递归

主循环：`LP → support → portfolio → force → 重解 → …`。每个 force 都是全局有效约束；把 $F^{\mathrm{force}}$ 写进节点边界等价于给原问题加「$s_i\in E_i$」的域约束。若重解后 $\mathrm{LP}(C,\mathrm{bounds})$ 不可行，则按 QNC 的叶子规则提取证书、记入 $L$，返回 NO。所以 NO 的最终证明对象仍然是**一个全局有效的 Farkas 叶子证书**；force 只影响搜索路径，不进入受信基。

### 2.5 严格性判据（局部）

在同一节点、同一割集 $C$、同一 force 状态下，若

$$\forall t\in E_i:\ \mathrm{LP}(C,\{(i,t)\})\ \text{可行},\qquad \mathrm{LP}(C,E_i)\ \text{不可行},$$

则这个 set force **严格强于**任何单列探针（单列探针在此节点拿不到任何 force，而 set 探针收缩了域）。这是可执行的判据；本轮用它做见证。

### 2.6 anytime 状态

$$S=(C,\ Q,\ F^{\mathrm{force}},\ L,\ E\text{-events},\ B,\ B_p,\ \text{re-solve 计数})$$

不变式：$C,Q,L$、force 事件表只增；$F^{\mathrm{force}}$ 只缩（force 取交）；$B,B_p$ 只增；预算增加时，固定配置下的轨迹是前缀（探针顺序与 LP 依赖只来自已发生的事件），已证 NO 不回退。

## 3. 算法

### 3.1 主过程

    function QSP_DECIDE(inst, h, budget):
        C = ∅; Q = ∅; force = {}; L = []; events = []
        res, z = solve_root_with_lazy_SD(C)          # 与 QNC/QUC 相同
        if res == INFEASIBLE: learn QNC leaf; return NO
        if z integral: return YES
        return SEARCH([(0,1)]*N, depth=0)

    function SEARCH(base, depth):
        loop = 0
        while True:
            bounds = APPLY_FORCE(base)
            if ∃i: domain_i(bounds) = ∅: return NO        # empty
            F = FORBIDS(bounds)
            if ∃E∈Q: E ⊆ F: return NO                     # clause prune
            res, z = SOLVE_WITH_LAZY_SD(bounds)           # 计 LP
            if res == INFEASIBLE: LEARN(F); return NO     # QNC 叶子
            if z integral: return YES
            if depth == 0: root_frac = True
            if probes_total < B_p and (depth == 0 or internal_budget > 0):
                kind = PORTFOLIO(bounds, z)
                if kind in (trap, cross, conflict): return NO
                if kind == force:
                    loop += 1; re_solves += 1; continue   # 闭合递归
            # ---- v7.1 中位数分支（兜底）
            (lo, hi2) = MEDIAN_SPLIT(z); 
            a = SEARCH(lo, depth+1); if a != NO: return a
            return SEARCH(hi2, depth+1)

### 3.2 portfolio 动作与顺序

     function PORTFOLIO(bounds, z):
         S = SUPPORT(z)
         A = []
         for i with S_i, live_i(bounds):
             span = (min S_i == min live_i and max S_i == max live_i)
             if span and |S_i| == 2:  A += [('unit',i,t) for t in S_i]
             elif not span:           A += [('set',i,S_i)] +
                                          [('unit',i,t) for t in endpoints(S_i)+interior]
             else:                    A += [('unit',i,t) for t in endpoints+interior]
         units-first: 先所有 span-2 单列动作，再非 span 的 set 动作，再其余单列
         limit = node_budget if depth==0 else internal_budget
         for act in A:
             if probes_total >= B_p or node_probes >= limit: break
             if act is unit: kind = DO_UNIT(i,t)     # v7.2 单列探针
             else:           kind = DO_SET(i,S_i)    # 2.1 支持删除
             if kind != None: return kind
         return None

    function DO_SET(i, S_i):
        got = PROBE_SUPPORT(i, S_i)                  # 2.1 + verify(forbid=E)
        if got is None: return None
        E, Φ = got
        jobs = {j : (j,t) ∈ E}
        if |jobs| == 1:
            j = the single job; E_j = {t : (j,t) ∈ E}
            cur = force.get(j, domain(j)); new = E_j ∩ cur
            if new == cur: return None
            if new == ∅: conflict = (j, cur, …, new, E, Φ); return conflict
            force[j] = new; events.append((j,new,E,Φ)); return force
        elif use_clause: Q.add(E)                    # 多任务 quorum 作为 clause
        return None

    function DO_UNIT(i,t):
        ok, Φ = PROBE_UNIT(i,t)                      # v7.2 单列探针
        if not ok: return None
        U.add((i,t)); L.add(({(i,t)},{(i,t)},Φ))
        force[i] = {t} ∩ force.get(i, domain(i))
        con = UNIT_CONFLICT(U)                       # 同任务陷阱 / 跨任务共识
        if con: return con
        return force

关键点：

- **顺序只影响预算命中，不影响正确性**：任何顺序、任何截断产生的 force/陷阱/冲突都由 2.2–2.3 保证 sound；未命中就回退 QNC。
- **set 动作兜底**：非 span 任务优先 set 探测（多点 quorum 的唯一来源），但仍排在 span-2 单列之后；`unit_probe=False` 时只跑 set 动作（ablation 里最差）。
- **force 闭合是主循环**：一次 force 后回到 `APPLY_FORCE + SOLVE`，而不是返回；`re_solves` 计数就是闭合迭代数。
- **提取失败不算结论**：`PROBE_SUPPORT` 的证书提取/验证失败只增加 `mine_fail`，返回 None，继续 portfolio 或回退。
- **资格感知**：essential scope 提取时把列键 $(i,k,t)$ 塌缩成原子 $(i,t)$（`(key[0],key[-1]) in F`），因此删除的是该时间的所有机器列；这是 2.1 定义的实现口径。

### 3.3 审计

    function AUDIT_QSP():
        if not QNC_AUDIT(L): return False
        for (i,t,Φ) in units:
            if not verify(Φ, forbid={(i,t)}): return False
        for (i,allowed,E,Φ) in events:
            if allowed == ∅: return False
            if not verify(Φ, forbid=E): return False
        if trap (i,t,u): check (i,t),(i,u) ∈ unit_certs and t ≠ u
        if cross:

            if prec: _,i,t,j,u = cross[:5]; check edge j ∈ succ(i),
                     u < t + p_i, and both unit certs
        if conflict:

            verify new cert at forbid=new_E
            if old cert: verify at old_E and old_allowed ∩ new_allowed = ∅
            else: check new quorum disjoint from original domain
        return True

- 252 例全部 `audit_qsp=True`；v7.2 QUC 在压力集第 24 例上因该 bug 为 False（见 5.5）。

### 3.4 预算与配置

- `probe_budget=24`：整次运行的单列 + set 探针总数；`node_budget=2`：根节点最多 2 次探针；`internal_budget=0`：默认不在内部节点探针（递归变体取 1）。
- `budget`、`nodecap`、`max_rounds`、`topk` 沿用 QNC；预算耗尽返回 UNKNOWN，不产生判决。
- 实测探针预算不紧：`probe_budget=6` 与 24 在 252 例上只差 4 LP（590 vs 594），最大单例探针数远小于 24。

## 4. 定理与证明

### 4.1 Farkas essential scope 引理

设 $C$ 有效割集，$z$ 是 $\mathrm{LP}(C)$ 可行解，$b_2$ 按 2.1 删列。若 $\mathrm{LP}(C,S_i(z))$ 不可行，则由 $b^Ty=-1$ 归一化得到的整数 $y$ 满足 $b^Ty=-1$，并且存在原子集 $E\subseteq S_i(z)$，使

$$\mathrm{LP}(C,E)\ \text{不可行}.$$

**证明**：对偶验证给出 $s_c=(A^Ty)_c\ge0$ 对所有未删列 $c$ 成立（否则提取失败，见 3.2 的 `mine_fail` 路径）；$E$ 收集所有 $s_c<0$ 的被删列并塌缩成原子。Arbitrary 可行点 $x$ 满足 $Ax=b,x\ge0$；把 $E$ 中原子对应的列全置零（2.1 的删除口径）后，$x_E=0$，于是

$$-1=b^Ty=(Ax)^Ty=x^TA^Ty=\sum_{c\notin E}x_c s_c\ \ge\ 0,$$

矛盾。所以这样的 $x$ 不存在，$\mathrm{LP}(C,E)$ 不可行。∎

### 4.2 quorum 子句定理

设 $E$ 如 4.1。每个可行整数调度的指标向量满足

$$\bigvee_{(j,t)\in E}(s_j=t).$$

**证明**：若某可行调度对所有 $(j,t)\in E$ 都有 $s_j\ne t$，其指标向量 $x$ 在 $E$ 的所有列上为 0，且 $Ax=b,x\ge0$，即 $\mathrm{LP}(C,E)$ 的可行点，与 4.1 矛盾。∎

### 4.3 set force 定理

若 4.2 的 $E$ 只含一个任务 $i$，则每个可行调度都有 $s_i\in E_i$；若已有 force $s_i\in F_i$ 且 $E_i\cap F_i=\varnothing$，则 NO。

**证明**：$E_i$ 定义直接给出第一句。第二句：由 4.2，$s_i\in E_i$；由 $F_i$ 的 force（同样是 4.2 的单任务特例），$s_i\in F_i$；两集不相交，矛盾。∎

### 4.4 force 闭合可靠性

设搜索在节点上按 3.1 依次安装 force $g_1,\dots,g_m$（每个都是 4.3 的全局域约束），最后 $\mathrm{LP}(C,\mathrm{bounds})$ 不可行。则原问题 NO，且 `_learn(F)` 记录的 QNC 叶子证书 $\Phi$（`verify(Φ, forbid=F)`，$F=\mathrm{forbids(bounds)}$）是全局有效的。

**证明**：每个 force 对原问题有效（全局子句 / 域约束），所以 $\mathrm{LP}(C,\mathrm{bounds})$ 是「原问题 + 所有 force」的松弛；它不可行说明原问题无可行整数调度。叶子证书的重放与节点边界无关（QNC 的 verify 只依赖原 inst 和 $F$），由 QNC v7.1 的叶子正确性定理保证。∎

注意：NO 判决不依赖「force 的发现顺序」或「哪个 force 最终导致不可行」；事件表只用于审计。

### 4.5 严格推广定理（含实验见证）

存在实例、节点与剖分，使某个 set force 满足 2.5 的严格性判据，即每个单点 $\mathrm{LP}(C,\{(i,t)\})$ 都可行而 $\mathrm{LP}(C,E_i)$ 不可行。本轮的可执行见证 7 例（5.5）：holdout47 job6 $\{2,8\}$、stress2/27/49 job6 $\{2,8\}$、stress5/31/42 job14 $\{2,3\}$；其中 stress49 在 depth=1。单列探针在这些点的 support 上无论扫多少列都得不到 force。

### 4.6 顺序无关性与完备性边界

- **顺序无关**：3.2 的任何动作顺序、任何 `probe_budget` 截断都只影响命中数量；每个已发生的 force/trap/cross/conflict 都是 4.1–4.3 的实例，sound。
- **完备性边界**：单列探针 + set 探针的组合**不是**所有 NO 的完备检测器。set 动作只对「非 span」任务触发（span-2 优先走单列），所以「span 任务上的严格多点 quorum」不在默认 portfolio 里；只有 `sets_first` 顺序才能看见（5.4 的 26 个多点事件）。预算截断也会让后续动作看不见。这是策略层的不完备，不是证明层的不可靠。
- **对照**：v7.2 的单列扫描对「同任务单列陷阱」完备（支持引理）；v7.3 的支持删除对「support 上任意多列 quorum」sound，但对「portfolio 是否能发现它」不作保证。

### 4.7 单调性与 anytime

固定配置下：令 $B_p^{(k)}$ 递增。算法是确定性的，LP/探针序列只依赖已发生事件；预算 $k$ 的轨迹直到第 $k$ 次探针与预算 $k+1$ 相同，所以已证 NO 不回退，节点数不增。QSP 的 anytime 形状与 QUC 在 201 上完全相同（$k=6$ 全部判 NO），在压力集上从 $k=5$ 起占优。

### 4.8 复杂度

- 根 LP / lazy 分离 / 中位数分支：与 QNC 相同，变量 $O(nmT)$，约束 $O(mT+n+|C|)$。
- 单列探针：1 次删列 LP + 1 次整数对偶提取（`farkas_int`）。
- set 探针：1 次删 support LP + 1 次整数对偶提取（`farkas_obj`，$b^Ty=-1$）+ 1 次 `verify`。
- force 闭合：每个 force 事件多 1 次节点 LP（`re_solves`）。
- portfolio 排序 $O(n\log n+|S|\log|S|)$；support 计算 $O(\mathrm{nnz}(z))$。
- 总 LP $\le B$，总探针 $\le B_p$，总节点 $\le$ `nodecap`。本轮 252 例：74 探针（QSP-2）/ 99（QSP-4/1）/ 181（QUC），`mine_fail=0`。

### 5.8 负结果与限制

1. **严格 set force 从未进入最优策略**：它的存在性（7 例）与可靠性都成立，但 sets-first / nounit 全面变差；默认 portfolio 只看 1 个多点事件。这是本轮最诚实的负结果。
2. **201 主表没有规模提升**：LP/节点与 QUC 相同；改进只体现在探针减半、证明形状、审计与压力集。
3. **17 个压力例与 QUC 不同，其中 2 个更差**：idx 24（6 vs 5 LP）、idx 28（28/14 vs 25/15）；idx 6 用 3 节点 vs 1（同 8 LP）。探针花了钱但没 force 时就是 overhead。
4. **递归层收益薄**：`depth>0` 的 force 仅 1 个；内部预算主要是「少走分支」的节点收益。
5. **根层只到 support 层的完备性**：portfolio 不保证发现所有 support quorum（span 任务的多点 quorum 要 sets_first 才可见）。
6. **v7.2 审计 bug 是真实缺陷**：201 例上无 cross 所以没暴露；证据在压力集第 24 例。v7.2 的 201/201 audit 结论仍然成立，但不能外推到含 cross 的语料。
7. **`mine_fail=0` 但有数值风险**：support 阈值 $10^{-7}$、DENS 舍入；更大实例可能提取失败（失败路径 sound，只会浪费探针）。
8. **YES 侧未测**：252 例全是 NO；force 闭合只影响 NO 侧。
9. **资格路径只做了小测**：35 例、2 个探针事件，不足以支撑统计结论。
10. **无统计功效**：压力集 51 例；201 主表只有 7 个根分数实例。

## 6. 风险与下一步

### 6.1 已知风险

1. **收益条件化（最大）**：主收益在压力集（根分数 51/51）与探针计数；201 主表不变。换到根 LP 普遍不可行的语料，QSP 等于 QNC 加一段不执行的代码；换到 span-2 很少、support 很大的语料，portfolio 可能先花探针再回退。
2. **set 算子未被策略兑现**：严格多点 quorum 的证明价值（7 例）与被 ablation 否定的性能价值并存；若评审只看主表，会低估它；若只看 ablation，会高估它。
3. **内部探针收益不明确**：节点 vs LP 的取舍（269/594 vs 283/577）没有理论指导，只是两档配置。
4. **顺序/预算对结论敏感**：sets-first、mixed、nounit 的差距很大；默认顺序是实验选出来的，有过拟合风险。
5. **审计修复改变 v7.2 结论边界**：跨任务路径的正确审计需要 `cross[1:5]`；依赖 v7.2 结果的下游要注意。
6. **force + 叶子的证明形状**：最终 NO 仍是 QNC 叶子证书；force 只用于审计。如果评审要求「force 本身构成证明」，需要把 force 闭合序列化成显式证明树（见 6.2）。
7. **数值/资格/YES 侧**：同 5.8 的 7–10。

### 6.2 下一步

1. **证明树序列化**：把 force 事件链 + 叶子证书写成独立 checker（事件表已有 $(i,E_i,E,\Phi)$，只差落盘格式）。
2. **严格方向的完备 portfolio**：让 span 任务也能走 set 动作（在单列动作连续失败后触发），并用 2.5 的判据在线判定「是否严格」，只保留严格多点 force。
3. **集合陷阱规则**：两个单任务 set force 的允许集不相交已经能判 NO（`_apply_mined_force` 的 conflict 路径），本轮 0 命中；构造能触发的语料，测「集合版陷阱」。
4. **多任务 quorum clause 的实验**：`_do_set` 已把多任务 $E$ 加入 clause 表，本轮只记录不实验；测它在 DFS 中的剪枝率。
5. **内层预算自适应**：用「上一步 force 是否命中」动态决定继续探针还是分支，替代固定 $r,r'$。
6. **support 结构分析**：统计 $|S_i|$、span 比例、严格多点比例与 LP/节点的关系，做「何时该用 set 探针」的决策规则。
7. **更强割下的 support 删除**：probe 只用当前 $C$；若在 probe 中学割，可能同时提高证书与命中率（成本更高）。
8. **anytime 交互**：把探针与分支按预算比例交错，而不是「根层先探完」。
9. **YES 侧与独立调度检查器**：对 YES 做资源/优先序复验。
10. **统计评估**：更多根分数与严格多点实例，报告均值/方差。
