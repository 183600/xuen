# 第 1 轮（新灵感循环 · 承接 UniBot-SAGE；本轮灵感：「避障控制」×「对话管理」）

> **基线承接声明**：UniBot-SAGE（定义 U1–U12 / 引理 L1–L7 / 实验 E601–E618）封存为“能力层”基线，编号不再改动。本轮**不换任务域**：仍是 Unitree G1 的 32 项桌面泛化操作、1 维 Dex1 夹爪、单 checkpoint 单 API、选手自部署 + 多端口远程评测。研究焦点从“把成功率做上去”转到“**让接触密集的操作在不确定障碍下安全地推进，并把‘让不让’变成一场有预算的对话**”。本线启用新编号：模块 **M1–M6**、定义 **SD1–SD12**、引理 **SL1–SL8**、实验 **E801–E820**。

> **数据纪律**：UniBot teaser 榜（`leaderboard_data.json`，检索 2026-11-17）仍是**占位表**，只作结构参照；本轮 §8 的合成 pilot 只用于**机制体检**，不冒充真机证据；§10 的文献只用于方法定位，不把“现有工作没做过”说成已证明的事实。

---

## 0. 一句话立论

桌面操作里的“避障”不是躲开所有物体，而是**在正确的时刻、以正确的接触关系，接近正确的物体**；因此安全层不能是“全接触禁令”，而应是一个**接触语义约束**。当策略意图与安全约束冲突时，一次投影会死锁或毁掉任务，所以需要一个**有回合、有记忆、有探测、有修复、有终止的对话管理器**来仲裁。合起来：**用对话管理来组织避障控制**。

---

## 1. 直觉解释（第一性原理）

### 1.1 灵感 A ·「避障控制」：安全不是“零接触”，是“接触的语义”

**第一性原理**：移动机器人避障的物理是“保持距离”；桌面操作的物理是“建立接触”。抓取、插入、拧开、放置都要求与目标或支撑面接触。把所有物体一视同仁地推远，会同时推走任务目标——**零接触 = 零成功**。

**三个不可回避的事实**：
1. **接触是任务的一部分**。目标物（target）必须被接触；支撑面（support）常被允许轻触；干扰物（distractor）通常禁止接触；人（human）绝对禁止接触。四类对象的“允许接触”语义完全不同，不能用同一个屏障函数。
2. **障碍不是确定集合，而是信念**。5 类泛化场景（位置 / 干扰物 / 背景 / 未见物品 / 人为干扰）里，遮挡、未见过物体、人的快速运动让“哪里有障碍、它是什么”本身不确定。确定性 CBF 会要么过度保守（把不确定性当实体，锁死），要么过度激进（把实体当噪声，撞上）。
3. **任务需要“接近”，安全需要“远离”**。这两者在目标物附近天然冲突。纯安全层如果把冲突一律判为“禁止”，就会在最后一环（对齐 / 插入）把成功率打回零。

**由此得到本轮的第一个转向**：把“避障控制”重新定义为 **接触语义约束下的机会约束控制**：
- 对每类对象定义接触模式 `MUST / MAY / NEVER`（见 SD2）；
- 对 `NEVER` 用机会约束 CBF 保持正距离（见 SD3–SD4）；
- 对 `MUST` 不设“禁止接近”，而是设“允许接触的流形”，只惩罚过度穿透；
- 风险预算按类别分配：人 > 干扰物 > 支撑面 > 目标（见 SL6）。

### 1.2 灵感 B ·「对话管理」：策略不是独白，是“提议—质疑—澄清—修复—承诺”

**第一性原理**：现在的 VLA 基本是“独白式”的——看一眼，吐一大段 action chunk，然后祈祷。人在不确定时不会这样；人会**提议、确认、改口**。所谓对话管理，本质不是“会聊天”，而是**在不确定性下决定“下一步该获取信息还是该行动”**。它由四件事构成：

1. **对话状态 = 信念，不是事实**。任务阶段、物体类别/位姿、抓握/接触状态，都是分布而非标签。
2. **对话动作 = 有信息代价的动作**。不只是“说话”，还包括**探测性动作**：轻抬 1–2 cm 验证是否夹住、换个视角看一眼验证是否对齐、减速靠近以降低位姿不确定性。
3. **对话策略 = 何时停止**。信息价值 < 动作代价就闭嘴执行（commit）；否则继续问（probe）。无预算的对话是拖延，不是智能。
4. **接地（grounding）= 双方对“说的是哪个东西”有共同指称**。策略说的“目标”和安全层看到的“障碍”必须落在同一个场景图节点上，否则 veto 和 repair 都是错的。

**映射到 UniBot**（注意：这里没有人类用户可以对话；对话是**系统内部协议**）：
- **提议者** = VLA 策略：给出一个 action chunk；
- **质疑者** = 安全层 + 感知层：给出 `VETO(j)` / `EXPLAIN(j)`；
- **管理者** = 对话管理器：决定 `REPAIR / PROBE / REQUEST_ALT / YIELD / COMMIT / FALLBACK / ABORT`；
- **世界** = 被探测、被等待、被绕开的对象。

**对话管理解决纯滤波器的三个死穴**：
- **死锁**：滤波器反复 veto，策略反复给同一个动作，机器人原地卡死；对话用 `REQUEST_ALT` 强制换提议，用 `ABORT` 及时止损。
- **震荡**：滤波器把动作拉回安全集，策略下一步又推出去，形成极限环；对话用 `REPAIR` 的残差记忆和 `YIELD` 的驻留时间打破循环。
- **过度保守**：把目标物当障碍，成功率归零；对话用 `grounding` + `PROBE` 区分“该抓的”和“该躲的”。

### 1.3 合成：四层栈 + 一条契约

**四层栈**：
1. **语义接地层（M1）**：语言 + 四路相机 → 带类别概率的场景图，区分 T/D/S/H，并给出位姿不确定性。
2. **接触感知避障层（M2）**：类别的接触语义 + 机会约束 CBF + 轨迹级 QP 修复。
3. **有界对话层（M3）**：在“修复代价 / 探测信息增益 / 换提议 / 等待 / 回退”之间做有限回合的仲裁。
4. **活性与审计层（M4–M6）**：进展监控、认证回退、风险自适应 chunk、可重放的对话转写。

**一条契约（安全-活性契约）**：
- **安全是无条件的**：任何被执行的 chunk 都必须通过机会约束认证；认证失败则进入认证回退。
- **活性是有条件的**：只有在“存在安全可行路径 + 对话公平 + 探测有正信息增益”时，才承诺进展；否则**尽早宣告不可行**，而不是拖到超时。
- 这条契约把“安全”和“成功率”从互相拆台变成可分别验收的两个目标：安全看违规率，活性看安全进展率（safe progress rate）。

**为什么现在做**：UniBot 的评测面同时给了三个条件——人为干扰场景（动态障碍）、干扰物/未见物品（语义不确定性）、1 维夹爪无触觉（接触不可直接观测），再加上官方会采集延迟与动作规律性（对话转写正好是可审计的产物）。这四个条件让“接触语义 + 有界对话”既有必要性，也有可测量性。

## 2. 瓶颈与可检验假设

| 观测 / 现有做法 | 问题 | 本轮假设 |
|---|---|---|
| 全接触禁令（把目标也当障碍） | 安全但成功率归零；把任务目标推走 | **H1（接触语义）**：按 T/D/S/H 分配接触模式，能在不牺牲安全的前提下恢复成功率 |
| 纯 veto 型安全层（违反就停） | 成功率崩塌、原地卡死 | **H2（修复优于否决）**：最小偏差修复显著优于 veto-only，且修复代价可界定 |
| 纯投影修复 | 在窄通道 / 动态人附近反复死锁 | **H3（对话优于单次修复）**：有界对话（换提议 / 探测 / 等待 / 回退）进一步降低 stuck 率并降低碰撞 |
| 位置型 CBF 处理动态人 | 人比机器人快时，位置约束来不及 | **H4（预测 + 让行）**：速度预测 + `YIELD` 能把人干扰碰撞压到低水平；代价是 stuck 上升，需要活性监控 |
| 语义分类错误 | 把干扰物当目标 = 碰撞；把目标当干扰物 = 死锁 | **H5（接地是总开关）**：分类错误率决定整套方案的上界；必须用保守回退 + 主动探测兜底 |
| 官方按 chunk 执行、并审计延迟 | 每步高频安全滤波不可假设 | **H6（chunk 级认证）**：在 chunk 生成时做轨迹级认证 + 风险自适应短 chunk，可在 105 ms 量级预算内落地 |

**上一轮（UniBot-SAGE）的三条结论继续有效**：终态成功是唯一计分货币（T1）；通用 = 技能组合（T2）；断点在最后一环（T3）。本轮的“最后一环”不再只指抓握/插入，而是**最后一环的接触是否被正确分类、正确验证、正确修复**。

## 3. 研究问题（本轮版）

- **Q1（接触语义的可学性）**：在语言指令 + 四路相机的条件下，能否把每个场景节点分到 T/D/S/H，并给出校准的类别概率？未见物品上的错误率与错误方向（把 T 误判为 D，还是反过来）哪个更致命？
- **Q2（机会约束的校准）**：类别相关的风险预算 `δ_c` 如何从数据/真机事故率标定？机会 CBF 的可靠性图能否在未见物体上保持单调？
- **Q3（对话的边际价值）**：在同样的安全约束下，`REPAIR`、`PROBE`、`REQUEST_ALT`、`YIELD`、`FALLBACK` 各自贡献多少成功率/安全性？对话的回合预算 `K` 与延迟预算如何权衡？
- **Q4（安全-活性契约）**：什么条件下可以承诺“安全进展”？何时应当 `ABORT` 而不是继续尝试？如何用 stall 监控避免“安全地卡死”？
- **Q5（工程语义）**：官方评测端如何执行 chunk、是否插值、是否跟踪 pivot？在只能按 chunk 调用的接口下，轨迹级认证 + 短 chunk 的真实延迟分布是什么？

## 4. 设计原则

- **P1 接触语义优先**：先定义“什么对象、什么阶段、允许什么接触”，再谈避障；禁止用单一屏障函数处理所有对象。
- **P2 安全是硬约束，进展是软目标**：任何执行动作必须通过认证；进展只在安全集内优化。
- **P3 有界对话 + 认证回退**：对话最多 `K` 回合；超时/无解必须进入认证回退，不允许无限协商。
- **P4 先探测再保守**：类别/位姿不确定时，优先用 `PROBE` 降熵；无法降熵时按“最坏类别”保守处理。
- **P5 单模型、单 API、零评测侧利用**：对外仍是一个策略服务；不读取评测侧私有信息，不硬编码任务分支，不做“脚本化”动作。
- **P6 可审计**：每次 veto / repair / yield / fallback 都留下时间戳、约束 id、slack、代价与延迟，形成可重放的对话转写。

## 5. 最小可提交闭环（MVP）与退化链

**MVP = M1（语义接地，低频缓存） + M2（接触感知机会 CBF，轨迹级） + M3（规则版有界对话） + M4（活性监控 + 认证回退） + M6（审计） + 通用 VLA 基线。**

先做规则版对话，不做学习版：规则版能跑通、能审计、能在真机 A/B 中量化每个 act 的边际收益；学习版只有在规则版给出正信号后才推进。

**严格退化链（任一环节不可用 ⇒ 行为回退而非漂移）**：
- **L0 语义接地不可用**（类别置信度低）⇒ 退回“所有非目标物体一律 NEVER + 目标按 MAY”的保守矩阵；
- **L1 机会 CBF 不可用**（QP 求解超时）⇒ 退回“标称轨迹 + 速度缩放 + 保持距离”的几何安全层；
- **L2 对话管理器不可用**（回合超预算）⇒ 退回“单次修复 + 失败即停”；
- **L3 活性监控不可用**（进展信号噪声大）⇒ 退回固定回合预算 + 认证回退；
- **L4 整条新链路失效** ⇒ 退回**纯 UniBot-SAGE 基线**（永远保留一份能跑通、可信度合规的最小提交）。

## 6. 预期贡献（可验收）

1. **接触语义矩阵**：给出 T/D/S/H × 阶段的 `MUST/MAY/NEVER` 形式化，并证明“目标 MAY”相对“全接触禁令”严格扩大可行集，同时不放松对 D/S/H 的约束（SL4）。
2. **接触感知机会 CBF**：把类别相关风险预算、位姿不确定性、动态人预测统一进一个可实时求解的约束集，并给出整段 episode 的联合违规上界（SL1/SL6）。
3. **有界对话协议**：给出对话动作集、对话状态、终止条件与安全-活性契约；证明有限回合终止（SL2）与修复代价界（SL3），并给出活性成立的条件（SL5）。
4. **风险自适应 chunk**：把“风险越高、chunk 越短”变成可计算的调度规则，使轨迹级认证在 105 ms 量级预算内可落地（SL7），并与上一轮 IP-03 的 chunk 缝合兼容。
5. **可审计对话转写**：把安全决策变成可重放、可解释的工程产物，对齐官方“延迟 / 动作规律性 / 可信度”口径（SL8）。
6. **一个诚实的 pilot**：在 2D 抽象上量化“全接触禁令 / veto-only / 投影修复 / 有界对话”的差异（§8），明确它只验证机制、不验证真机。

## 7. 本轮最大风险（一句话）

**最大风险：整套安全性押在“目标 / 干扰物 / 支撑面 / 人”的语义分类上，而未见物品与人为干扰恰恰是分类最不可靠的场景——一次把干扰物误判为目标，安全层就会为碰撞开绿灯；一次把目标误判为干扰物，安全层就会把任务锁死；对话只能放大或放大不了这个错误，不能从根本上纠正它。**

## 8. 下一轮迭代计划（深化与修剪，不推倒重来）

- **深化**：
  1. 把规则版对话升级为**有限视界 VOI 规划**：`PROBE` 的价值 = 期望熵减 × 单位信息收益 − 探测延迟；`REQUEST_ALT` 的价值 = 修复代价下降的期望。
  2. 把类别概率从“单帧分类”升级为**时序信念**（场景图 + 跟踪 + 语言指称），并输出校准曲线。
  3. 把动态人从“恒速预测”升级为**交互意图预测**（人是否会为机器人让行），把 `YIELD` 的时机作为可学习参数。
  4. 把接触语义矩阵从手工规则升级为**从官方数据中估计**：用“物体随动 / 夹爪闭合 / 阶段标签”自动生成 MUST/NEVER 的弱标签。
- **修剪预案**：
  - 若语义接地在未见物体上的**目标-干扰物混淆率**超过阈值（例如 >15%），则**砍掉“目标 MAY”的精细语义**，只保留“人/非人”二分 + 全非人保守避障，并把资源转回 IP-02 的抓握确认。
  - 若轨迹级 QP 的 p99 超过延迟预算，则**只对短 chunk 做认证**，长 chunk 退回几何安全层。
  - 若 pilot 的“对话 vs 投影”增益在真机上消失（真机 A/B 的 95% 区间跨 0），则**冻结对话学习**，只保留 `YIELD` 与 `FALLBACK` 两个安全必需 act。
- **保留项**：M2（接触感知机会 CBF）、M4（活性 + 认证回退）、M6（审计）在任何情况下不砍；它们不依赖学习，机制正确性可独立验证。

## 0. 本轮结论摘要

**一句话路线**：把「避障控制」编译成**接触语义下的机会约束控制**，把「对话管理」编译成**策略 / 安全 / 感知之间的有界协商协议**，再用一条**安全-活性契约**把两者焊死：

`M1 语义接地 → M2 接触感知机会 CBF → M3 有界对话仲裁 → M4 活性监控 + 认证回退 → M5 风险自适应 chunk → M6 审计转写`

**三条设计承诺**：

| 承诺 | 含义 | 可验收形式 |
|---|---|---|
| **接触不是碰撞** | 目标物 / 支撑面 / 干扰物 / 人 的接触语义不同；安全层不能一视同仁 | 接触语义矩阵 + “目标 MAY” 的可行集严格包含“全接触禁令”的可行集（SL4） |
| **否决不是修复** | 纯 veto 会把任务锁死；必须允许最小偏差修复，修复不成再换提议 | 修复代价界（SL3）+ pilot 中 veto-only vs 投影 vs 对话的对照（§8） |
| **安全不等于卡死** | 安全是无条件的，进展是有条件的；无解要尽早宣告，不许拖到超时 | 安全-活性契约 + 有界终止（SL2）+ 活性条件（SL5） |

## 2. 创新点详述

### IP-SD1 · ContactGround 语义接触接地（P0）

- **动机**：整套安全层的第一块多米诺骨牌是“这是什么对象”。把干扰物当目标 → 为碰撞开绿灯；把目标当干扰物 → 把任务锁死。5 类泛化场景里，未见物品与人为干扰恰好是分类最不可靠的地方。
- **与现有方案的差异**：现有 VLA 大多把“障碍”当作一个无类别的距离场（或只做目标检测）；我们把**接触语义**作为一等公民：每个节点输出 `(P(T), P(D), P(S), P(H))` 与位姿协方差，后续 CBF 直接消费这些量，而不是消费一个硬标签。
- **技术可行性**：高–中。可复用开放词表检测/分割（语言指称 → 目标节点），其余节点按“非目标”处理；支撑面可用平面/桌沿几何先验；人可用人体检测 + 运动预测。低频（5–10 Hz）更新，跟踪缓存；高频控制只用缓存的类别与膨胀半径。
- **所需资源**：数据 = 官方 32 数据集 + 自建 OOD 变体（遮挡 / 干扰物 / 背景 / 未见物品）；算力 = 检测/分割模型蒸馏到单卡可跑；接口 = 无新增字段（只在服务内部用 `observation.language` 与四路相机）。
- **落地步骤**：
  1. 用语言指称 + 检测/分割建立场景图，标注 T/D/S/H 四类弱标签（目标来自指令；人来自人体检测；支撑面来自平面拟合；其余为 D）。
  2. 训练/蒸馏类别头与位姿不确定性头；输出温度校准后的概率（可靠性图）。
  3. 定义“类别不确定”的保守回退：最大类别概率 < τ_cls 时，按**最坏类别**处理（T 的邻居按 D 处理；D 的邻居按 H 处理），并触发 `PROBE`。
  4. 在未见物品/遮挡场景上做混淆矩阵，专门看“T→D”和“D→T”两个方向的代价。
- **风险**：①类别错误是总开关（见 §9）；②检测/分割延迟挤占预算 ⇒ 低频 + 缓存 + 只在短 chunk 前刷新；③语言指称歧义（“杯子”有多个）⇒ 用空间关系 + 交互历史消歧，必要时 `PROBE`。

### IP-SD2 · ContactCBF 接触感知机会 CBF（P0）

- **动机**：桌面操作要求接触目标，但必须避免碰到干扰物/人；同时感知有噪声。确定性 CBF 要么过度保守，要么在噪声下失效。
- **与现有方案的差异**：不是“一个距离场 + 一个安全阈值”，而是：
  - **类别相关接触模式** `MUST / MAY / NEVER`；
  - **类别相关风险预算** `δ_H < δ_D < δ_S < δ_T`；
  - **机会约束**：用 `κ(δ)σ` 膨胀不确定障碍，而不是用固定 margin；
  - **chunk 级轨迹 QP**：在发出的整个 action chunk 上认证，而不是假设评测端让我们每一步高频滤波。
- **技术可行性**：中–高。G1 手臂可用关节速度/位置的运动学模型做短时预测；物体位姿用 IP-SD1 的估计；动态人用恒速/恒加速预测 + 不确定性膨胀。短 chunk（1–4 步）时 QP 很小；长 chunk 在自由空间通常无活跃约束，可快速通过。
- **所需资源**：算力 = 每 chunk 一个小 QP（≤24 约束）；数据 = 无需新数据（几何 + 不确定性）；接口 = 无新增字段。
- **落地步骤**：
  1. 用官方数据拟合关节 ↔ EE 的短时运动学（或直接用解析 Jacobian），验证 1–4 步预测误差。
  2. 实现接触语义矩阵与机会约束；先做“静态障碍 + 固定 margin”版本，再逐项加不确定性、动态人、类别预算。
  3. 实现 chunk 级 QP：目标 = 最小偏差 + 平滑；约束 = CBF + 关节/速度限幅；输出冲突集（哪些约束不可行）。
  4. 与 IP-SD5 联动：风险高时把 chunk 截短到第一个活跃约束之前。
  5. 真机 A/B：对比“全接触禁令 / 语义 CBF / 语义 CBF + 机会约束”。
- **风险**：①运动学模型与真机不符 ⇒ 用保守误差界 + 短 chunk；②机会约束的 δ 难标定 ⇒ 先按事故率给保守值，再用 pilot/真机校准；③QP 不可行 ⇒ 交给对话层（IP-SD3），不硬解。

### IP-SD3 · BoundedDialog 有界对话仲裁（P0）

- **动机**：纯 veto 会死锁；纯投影会在窄通道/动态人附近反复卡死；需要“换提议、探测、等待、回退”的回合结构。
- **与现有方案的差异**：把安全层从“过滤器”升级为“对话参与者”：
  - 策略 `PROPOSE` 一个 chunk；
  - 安全层 `VETO(j)` / `EXPLAIN(j)`（给出冲突约束与 slack）；
  - 管理器选择 `REPAIR`（最小偏差投影）、`REQUEST_ALT`（带约束偏置的重新提议）、`PROBE`（降熵探测）、`YIELD`（让人/动态障碍先过）、`COMMIT`、`FALLBACK`、`ABORT`；
  - 每个决定最多 K 回合，超时进入认证回退。
- **技术可行性**：高（规则版）/ 中（学习版）。规则版用“可行性 + 修复代价 + 人距离 + stall”即可跑通；学习版用有限视界 VOI 或小规模 RL 在仿真中训练，安全约束用硬 mask。
- **所需资源**：规则版几乎零算力；学习版需要仿真环境（可用 IP-06 的 OOD 切分 + 自建 2D/3D 障碍场景）；接口 = 无新增字段。
- **落地步骤**：
  1. 实现规则版对话状态机（COMMIT / REPAIR / REQUEST_ALT / PROBE / YIELD / FALLBACK / ABORT）。
  2. 在 pilot（§8）与官方数据回放上量化每个 act 的边际贡献。
  3. 把 `PROBE` 的 VOI 形式化（熵减 × 收益 − 延迟），先做规则阈值，再做学习。
  4. 在真机难任务（Unlock / Plug In Ethernet / Open Pill Bottle）上做 A/B：只开 REPAIR、再开 REQUEST_ALT、再开 PROBE/YIELD。
- **风险**：①对话变成拖延 ⇒ 硬回合上限 + 延迟预算 + 超时回退；②`PROBE` 破坏场景（碰到别的物体）⇒ 探测动作也必须过安全认证；③规则阈值过拟合 pilot ⇒ 真机 A/B 与 OOD 场景双重验证。

### IP-SD4 · LiveGuard 活性监控 + 认证回退（P0）

- **动机**：安全层最危险的失败不是“撞了”，而是“安全地卡死到超时”。在只计成功率的榜单上，卡死 = 失败，而且比碰撞更隐蔽。
- **与现有方案的差异**：把“活性”当作与“安全”并列的一等目标：
  - 定义进展势 `Φ`（到目标的距离 + 阶段奖励）；
  - 监控 stall（连续 W 步无进展）；
  - stall 时升级：换提议 → 探测 → 让行 → 回退；
  - 认证回退 `π_fb` 必须在一个可证明的 invariant set 内，且只作用于有限步。
- **技术可行性**：高。规则 + 阈值即可；难点是“进展”的信号在长程任务上噪声大，需要阶段标签（可复用 IP-06 的六因子）。
- **所需资源**：算力极小；数据 = 阶段标签（IP-06）；接口 = 无新增字段。
- **落地步骤**：
  1. 定义 Φ 的分段形式（reach / grasp / transport / align / insert / release）。
  2. 实现 stall 计数与升级策略；在 pilot 中调 W 与升级顺序。
  3. 设计认证回退：刹车 / 后退 / 保持；用 CBF 验证回退动作本身安全。
  4. 真机：统计“假回退”（本可继续但被回退）与“真回退”（避免超时）的比例。
- **风险**：①Φ 噪声导致误回退 ⇒ 用多信号（距离、接触、阶段）融合；②回退也可能撞（动态人）⇒ 回退动作同样过 CBF；③回退后无法恢复 ⇒ 回退只承诺“安全”，不承诺“能继续”。

### IP-SD5 · RiskChunk 风险自适应 chunk（P1）

- **动机**：官方按 chunk 调用；我们无法假设评测端允许每步高频滤波。风险高时 chunk 必须短，才能在下一个观测到来前及时改口；自由空间 chunk 可以长，以降低调用次数与延迟抖动。
- **与现有方案的差异**：把 chunk 长度从固定超参变成**风险的函数**：
  `T_a = clip(⌊c · h_min / (v_max · Δt)⌋, T_lo, T_hi)`
  其中 `h_min` 是当前预测轨迹上的最小安全裕度，`c` 是保守系数。近障碍/人时 `T_a` 降到 1–3；自由空间回到 8–16。
- **技术可行性**：高。与上一轮 IP-03 的缝合器兼容：短 chunk 边界仍用一阶外推 + 残差保证 C0。
- **所需资源**：算力极小；接口 = `action_chunk_size` 元数据里声明上限，运行时在合法范围内自适应。
- **落地步骤**：
  1. 实现 `h_min` 的预测（用 IP-SD2 的轨迹传播）。
  2. 用 pilot 扫 `c` 与 `T_lo/T_hi`，看成功率/延迟/回合数的 Pareto。
  3. 真机验证：短 chunk 是否增加调用次数到不可接受；评测端是否有隐藏的 chunk 假设。
- **风险**：①短 chunk 增加调用次数 ⇒ 并发与延迟压力；②评测端可能对 chunk 长度有隐含假设（需先复刻官方 client 语义）；③过度截短导致动作不连贯 ⇒ 缝合器 + 平滑约束兜底。

### IP-SD6 · DialogLedger 对话审计（P1）

- **动机**：官方明确会采集 per-step 延迟、波动与动作统计规律性，并可能据此评估可信度。把安全决策变成可审计产物，既降低“不可信”风险，也为调试提供证据。
- **与现有方案的差异**：大多数提交只保证“能跑”；我们把每次 `VETO / REPAIR / PROBE / YIELD / FALLBACK` 都记录为一条带时间戳、约束 id、slack、代价、延迟的记录，并做哈希链，支持确定性重放。
- **技术可行性**：高（工程活）。
- **所需资源**：极小；接口 = 官方 client 的响应字段（延迟、动作）。
- **落地步骤**：
  1. 定义 transcript schema（t, port, act, constraint_id, slack, distortion, latency, action_hash, prev_hash）。
  2. 在 `get_action` 中埋点；导出 JSONL / 汇总报告。
  3. 实现确定性重放：给定 obs 序列 + 随机种子，复现动作序列；不一致即告警。
  4. 生成延迟 p50/p99、jerk 分布、fallback 率、对话回合分布。
- **风险**：①记录本身增加延迟 ⇒ 异步写、无锁环形缓冲；②“动作过于规律”被误判为脚本化 ⇒ 保留策略固有随机性，不做人工拟人化噪声；③日志含敏感信息 ⇒ 只记录结构与数值，不记录原始图像。

## 3. 符号与定义（SD1–SD12）

| 符号 | 含义 |
|---|---|
| `x_t` | 机器人状态（关节位置/速度，或 EE 位姿/速度） |
| `a_t` | 动作（关节速度/位置增量，或 EE 速度/位姿增量） |
| `o_j` | 场景节点 j（物体/支撑面/人） |
| `c_j` | 类别 ∈ {T, D, S, H}（目标 / 干扰物 / 支撑面 / 人） |
| `ξ_j, Σ_j` | 节点 j 的位姿估计与协方差 |
| `b_t` | 语义场景信念（节点、类别概率、位姿分布） |
| `φ_t` | 任务阶段 ∈ {reach, grasp, lift, transport, align, insert, place, release, unknown} |
| `M(c, φ)` | 接触语义矩阵：`MUST / MAY / NEVER` |
| `h_j(x)` | 节点 j 的语义屏障（带符号距离减去半径与裕度） |
| `δ_c` | 类别 c 的风险预算（机会约束的违反概率上界） |
| `κ(δ)` | 高斯分位数（`Φ^{-1}(1-δ)`） |
| `T_a` | action chunk 长度 |
| `K` | 单次决策的最大对话回合数 |
| `Φ_t` | 进展势（progress potential） |
| `π_fb` | 认证回退策略 |
| `Ξ` | 对话转写（transcript） |

**定义 SD1（语义场景信念）**
`b_t = { (j, P(c_j | o_{1:t}, ℓ), p(ξ_j | o_{1:t}), Σ_j) }_{j=1..m} ∪ {ρ}`，其中 `ℓ` 是语言指令，`ρ` 是语言指称到场景节点的关联分布。`b_t` 是后续安全层的唯一输入，而不是硬标签。

**定义 SD2（接触语义矩阵）**
`M: {T,D,S,H} × Φ → {MUST, MAY, NEVER}`。默认：
- `M(T, grasp/insert/place) = MUST`（必须接触目标）;
- `M(T, transport) = MAY`（可接触，但不强制）;
- `M(S, ·) = MAY`（支撑面轻触允许）;
- `M(D, ·) = NEVER`（干扰物禁止接触）;
- `M(H, ·) = NEVER`（人绝对禁止接触）。
矩阵是**任务与阶段的函数**，不是常数；例如“把干扰物推开”任务可临时把某个 D 升为 MAY。

**定义 SD3（语义屏障）**
对节点 j，令 `d_j(x)` 为机器人到 j 表面的最短距离，`r_rob` 为机器人包络半径，`r_j` 为节点半径，`m_j = κ(δ_{c_j}) σ_j` 为不确定性膨胀。定义：
- `NEVER`: `h_j(x) = d_j(x) - r_j - r_rob - m_j`，要求 `h_j ≥ 0`；
- `MAY`: `h_j(x) = d_j(x) - r_j - r_rob`，要求 `h_j ≥ -ε_s`（允许小穿透/接触）；
- `MUST`: 同 `MAY`，但 `h_j ≥ -ε_pen` 只惩罚过度穿透；接触由任务奖励驱动，而不是由安全层强制。
其中 `ε_s, ε_pen` 由材料/力控安全上限给出。

**定义 SD4（接触感知机会约束安全滤波器）**
给定标称 chunk `a^p_{1:T}`、初始状态 `x_0`、信念 `b`、阶段 `φ`，求解
```
min_{a_1..a_T}  Σ_t ||a_t - a^p_t||_W^2 + λ Σ_t ||a_t - a_{t-1}||^2
s.t.  x_{t+1} = f(x_t, a_t)
      ∀ t, j:  M(c_j, φ_t) = NEVER  ⇒  h̄_j(x_t) ≥ κ(δ_{c_j}/T) σ_j(x_t)
      ∀ t, j:  M(c_j, φ_t) = MAY    ⇒  h̄_j(x_t) ≥ -ε_s + κ(δ_{c_j}/T) σ_j(x_t)
      ∀ t, j:  M(c_j, φ_t) = MUST   ⇒  h̄_j(x_t) ≥ -ε_pen + κ(δ_{c_j}/T) σ_j(x_t)
      a_t ∈ A（关节/速度/加速度限幅）
```
其中 `h̄_j` 是用估计位姿 `ξ_j` 计算的屏障，`σ_j` 是沿屏障法向的不确定性。若可行，返回 `a^*` 与修复代价 `d = ||a^* - a^p||_W`；若不可行，返回冲突集 `C`（不可满足的约束 id 集合）。

**定义 SD5（对话状态）**
`s_t = (b_t, φ_t, Φ_t, d_t, κ_t, τ_t, H_t, ρ_t)`，其中 `d_t` 是当前修复代价，`κ_t` 是当前最小 slack，`τ_t` 是已用回合数，`H_t` 是冲突历史（哪些约束反复出现），`ρ_t` 是语言指称关联置信度。

**定义 SD6（对话动作集）**
`A_d = { PROPOSE, VETO, EXPLAIN, REPAIR, PROBE, REQUEST_ALT, YIELD, COMMIT, FALLBACK, ABORT }`。语义见 §4 的对话管理器伪代码；每个动作都有前置条件与后置条件，不能无条件触发。

**定义 SD7（对话策略）**
`π_d: S → Δ(A_d)`，在有限视界 `K` 内最大化
`J = E[ΔΦ] - λ_c · cost(act) - λ_r · risk(act) - λ_t · latency(act)`，
并以“所有被执行的 chunk 必须通过 SD4 认证”为硬约束。MVP 用规则/MPC 近似；学习版用带安全 mask 的 RL 或模仿规则版。

**定义 SD8（修复算子与代价）**
`R(a^p, C) = argmin_{a ∈ F(C)} ||a - a^p||_W`，`d = ||R - a^p||_W`。只允许在 `d ≤ ε_commit` 时直接 `COMMIT`；否则必须升级为 `REQUEST_ALT` / `PROBE` / `YIELD` / `FALLBACK`。这样“修复”不会悄悄把策略拉到一个完全不同的动作上。

**定义 SD9（接地的信息价值）**
令 `z` 为语言指称到节点的关联，`H(z | b_t)` 为其熵。`PROBE` 动作 `u` 的信息价值
`VOI(u) = E_{o'|u}[H(z|b_t) - H(z|b_{t+1})] · V_info - cost(u)`。
仅当 `VOI(u) > 0` 且探测动作本身通过 SD4 认证时才允许 `PROBE`。

**定义 SD10（进展势与活性）**
`Φ_t = -dist(x_t, goal) + Σ_φ w_φ · 1[phase φ completed]`。若连续 `W` 个决策 `ΔΦ_t < η`，触发 stall 升级：`REQUEST_ALT` → `PROBE` → `YIELD` → `FALLBACK`。若 `τ_t > K` 或 `Φ_t < Φ_abort`，执行 `ABORT`。

**定义 SD11（认证回退）**
`π_fb` 是一个预认证控制器（刹车 / 后退 / 保持），存在不变集 `S_fb` 与有限步 `T_fb`，使得从任意 `x ∈ S_fb` 出发，执行 `π_fb` 的 `T_fb` 步内始终满足所有 `NEVER` 的硬约束。`FALLBACK` 只执行 `π_fb`，不执行任何未认证动作。

**定义 SD12（对话转写）**
`Ξ = { (t, port, act, constraint_id, slack, distortion, latency_ms, action_hash, prev_hash) }`，哈希链保证不可篡改；给定相同的观测序列、随机种子与代码版本，`Ξ` 可确定性重放。

# ===== IP-SD3：有界对话管理器（规则版） =====
class BoundedDialogue:
    def decide(self, s, a_prop, ok, a_rep, info):
        # 0) 直接可行且偏差可接受：承诺
        if ok and info["distortion"] <= EPS_COMMIT:
            return "COMMIT", a_rep

        # 1) 可行但偏差大：先修复，修复不成再换提议
        if ok:
            if s.turn < K:
                return "REPAIR", a_rep
            return self.escalate(s, a_prop, info)

        # 2) 不可行：按“人 > 探测 > 换提议 > 回退”的优先级
        if self.human_too_close(s):
            return "YIELD", self.yield_action(s)
        if s.turn < K and self.voi(s) > VOI_COST:
            return "PROBE", self.probe_action(s)
        if s.turn < K:
            return "REQUEST_ALT", self.alternative(s, info["conflict"])
        return "FALLBACK", self.live.fallback(s)

    def escalate(self, s, a_prop, info):
        if self.human_too_close(s):
            return "YIELD", self.yield_action(s)
        if self.voi(s) > VOI_COST:
            return "PROBE", self.probe_action(s)
        if s.turn < K:
            return "REQUEST_ALT", self.alternative(s, info["conflict"])
        return "FALLBACK", self.live.fallback(s)

    def alternative(self, s, conflict):
        # 给策略加“远离冲突约束”的偏置，重新提议；不是硬编码任务分支
        bias = sum(self.away_vector(s, j) for j in conflict)
        return self.model.repropose(s, bias)

# ===== IP-SD4：活性监控 + 认证回退 =====
class LivenessMonitor:
    def update(self, s, a_exec, obs):
        phi = self.progress(s, obs)
        if phi < s.phi - ETA:
            s.stall = 0
        else:
            s.stall += 1
        s.phi = phi
        if s.stall >= W:
            s.escalate = True

    def fallback(self, s):
        # 只返回预认证的刹车/后退/保持动作；不做任何未认证的“聪明”动作
        return self.certified_brake(s.x)

## 5. 推导（引理 SL1–SL8）

**引理 SL1（安全组合）**
设在每个决策步 t、每个 `NEVER` 节点 j 上，执行的 chunk 满足机会约束
`P(h_j(x_t; ξ_j) ≥ 0) ≥ 1 - δ_j / (T · n_j)`，其中 `T` 为 episode 步数、`n_j` 为同类节点数，且不确定性模型校准。则由 union bound，
`P(∃t, j: h_j(x_t) < 0) ≤ Σ_j δ_j ≤ δ_global`。
若认证失败进入 `π_fb`，且 `π_fb` 在 `S_fb` 上保持同样的硬约束，则上述界对整段 episode 仍成立。∎
> 关键假设：机会约束的“概率”是对真实 `ξ_j` 的，而不是对线性化后的 `h̄_j`；若模型失配，需用鲁棒 margin 或在线校准。

**引理 SL2（有限终止）**
单次决策最多 `K` 回合；stall 监控在 `W` 个决策内触发升级；升级链有限（`REQUEST_ALT → PROBE → YIELD → FALLBACK → ABORT`）。因此一次 `get_action` 与整段 episode 的对话都在有限步内终止，不存在无限 veto 循环。∎

**引理 SL3（修复最优性与代价界）**
SD4 的 QP 是严格凸的（`W ≻ 0`，约束为凸），故最优解唯一。若标称动作 `a^p` 可行，则 `a^* = a^p, d = 0`；否则对任意可行 `a_f`，有 `d = ||a^* - a^p||_W ≤ ||a_f - a^p||_W`。由于对话层只在 `d ≤ ε_commit` 时直接 `COMMIT`，任何被承诺的修复都满足 `d ≤ ε_commit`；否则一定升级。∎

**引理 SL4（接触语义的弱支配）**
令 `F_all` 为把目标也当作 `NEVER` 的可行集，`F_sem` 为把目标设为 `MAY` 的可行集。由于 `F_sem` 只是放松了目标约束、对 D/S/H 的约束完全相同，故 `F_all ⊆ F_sem`。因此，对任何以“接近目标”为目标的标称动作，投影到 `F_sem` 的可行性与可达目标集都不劣于投影到 `F_all`；而对 D/S/H 的安全约束一字未松。∎
> 注意：这保证的是“可行集不被安全层无谓地切掉”，不保证“策略一定能找到目标”；后者仍取决于策略与感知。

**引理 SL5（活性的条件性）**
定义安全进展图 `G`：节点为已认证状态；若存在一个认证 chunk 使 `ΔΦ ≥ -η`，则连边。若 `x_0` 到目标在 `G` 中存在路径，对话调度公平（每个正 VOI 的 act 最终被尝试），且探测动作能严格降低关联熵，则系统在有限期望时间内到达目标或宣告不可行（`ABORT`）。∎
> 这是**条件命题**，不是无条件保证；它把“活性”从口号变成了可检查的图连通性 + 公平调度 + 探测有效性三个前提。

**引理 SL6（风险预算与保守性）**
令 `m_j = κ(δ_j) σ_j`，`κ` 随 `δ_j` 递减。在总预算 `Σ_j δ_j ≤ δ_global` 下最小化总保守性 `Σ_j m_j` 是一个凸优化问题；其解把更大的 `δ`（更小的 margin）分给低后果、低不确定性的对象，把更小的 `δ`（更大的 margin）分给人与干扰物。于是 `δ_H < δ_D < δ_S < δ_T` 不是拍脑袋，而是预算约束下的自然分配。∎

**引理 SL7（实时开销界）**
设 chunk 长度 `T ≤ T_hi`、约束数 `m ≤ 24`。快速路径只做 `T·m` 次屏障评估，复杂度 `O(Tm)`；慢路径的轨迹 QP 变量数为 `T·dim(a)`，短 chunk（`T ≤ 4`）时可在毫秒级求解。若场景图以 5–10 Hz 刷新、跟踪缓存以 O(1) 读取，则每 chunk 的额外开销可控制在个位数毫秒，落在 105 ms 量级预算内。∎
> 这是**目标界**，需在 G1 部署栈上实测 p99；若超预算，按退化链缩短 chunk 或降低场景图频率。

**引理 SL8（审计可靠性）**
转写 `Ξ` 记录每个动作的约束 id、slack、修复代价、延迟与哈希链。给定相同的观测序列、随机种子与代码版本，若执行是确定性的，则重放产生相同的动作序列；任何不一致都意味着未声明的状态、非确定性来源或实现 bug。因此 `Ξ` 可作为“动作规律性 / 延迟可信度”的自证材料。∎

### 8.1 设置

- 2D 平面 `[0,1]²`，点末端，`v_max=0.08`，`dt=0.05`，`R_robot=0.015`，目标半径 `0.05`；成功 = 进入目标圆。
- 场景：
  - **clutter**：4 个静态干扰物，随机半径 0.03–0.065；
  - **narrow**：5 个干扰物，其中两个在目标前方形成窄通道；
  - **human**：3–4 个静态干扰物 + 一个在目标附近往返的人手（半径 0.045，`σ=0.02`，周期 200 步，幅值 0.18）。
- 感知：每个障碍的位姿加高斯噪声 `σ=0.018`；安全层用 `κ_D=2, κ_H=3` 膨胀；动态人用 0.6 s 恒速预测。
- 方法：
  - **B0**：只用策略（无安全层）；
  - **B1**：全接触禁令（目标也当障碍）；
  - **B2**：语义 CBF + veto-only（提案不安全就停）；
  - **B3**：语义 CBF + 投影修复（不可行才停）；
  - **B4**：语义 CBF + 有界对话（修复 / 换提议 / 探测 / 让行 / 认证刹车）。
- 每格 200 个随机种子，horizon 320 步；指标为成功率 / 非目标碰撞率 / stuck 率（三者相加为 100%）。

### 8.3 解读

1. **B1 证明“零接触 = 零成功”**：全接触禁令几乎不碰撞，但成功率 0–0.5%；这是最干净的“过度保守”证据。
2. **B2 证明“veto 不够”**：veto-only 比 B0 安全，但成功率在窄通道掉到 5%，stuck 62.5%；光会拒绝不会修复。
3. **B3 证明“投影修复有效但不完整”**：成功率大幅回升、碰撞很低，但 stuck 仍 26–50%；几何修复解决不了“该换提议/该等待”的问题。
4. **B4 证明“对话有边际价值”**：三个场景都取得最高成功率与最低碰撞；代价是 45–98 个对话回合/局、窄通道 1.33 次回退/局。这是“对话解决死锁”的第一个定量信号。
5. **人干扰是最难的轴**：B4 把碰撞从 B3 的 27% 压到 3.5%，但 stuck 升到 35.5%——安全-活性权衡是真实的，需要下一轮的意图预测与让行时机学习。
6. **不能过度解读**：2D、无动力学、无抓取/插入、无人反应、无真机延迟；这些数字只支持“机制方向”，不支持“真机收益”。

## 9. 风险登记册与剪枝预案

| 风险 | 概率 | 影响 | 对冲 |
|---|---|---|---|
| **语义接地错误**（T↔D/H） | 中高 | 高（碰撞或锁死） | 类别概率 + 最坏类别回退 + `PROBE`；E810 门槛；超过阈值退回保守矩阵 |
| **机会约束未校准** | 中 | 中高（安全名义值失真） | 可靠性图 + 真机事故率标定；保守 `δ`；鲁棒 margin |
| **对话变成拖延** | 中 | 中（超时） | 硬回合上限 K + 延迟预算 + 超时回退；E808 |
| **安全地卡死** | 中高 | 高（成功率归零） | LiveGuard + stall 升级 + 认证回退；E807 |
| **QP 不可行 / 超时** | 中 | 中 | 短 chunk + 快速路径 + 几何退化层；E808 |
| **动态人预测失准** | 中 | 高（人碰撞） | 加大 margin + 让行半径 + 人检测冗余；E806 |
| **评测端 chunk 语义未知** | 中 | 中 | 先用官方 client 复刻；不利用未声明行为；短 chunk 保守 |
| **过拟合 pilot** | 中 | 中 | 真机 A/B + OOD；pilot 只作机制排序，不作调参依据 |
| **动作过于规律被判脚本化** | 低中 | 中 | 保留策略随机性；不做人工拟人噪声；审计自证 |

**剪枝预案（下一轮起执行）**：
- **必保**：M2（接触感知机会 CBF）、M4（活性 + 认证回退）、M6（审计）。
- **优先深化**：M1（接地质量决定上界）、M3（对话的边际价值需真机确认）。
- **条件推进**：M5（chunk 自适应，依赖官方执行语义实测）。
- **暂存**：学习版对话、复杂人意图预测；规则版跑通前不做。

## 10. 与既有 UniBot-SAGE 的叠加方式

| SAGE 组件 | 本线如何复用 | 不改什么 |
|---|---|---|
| IP-01 SkillToken-MoE | 作为 `PROPOSE` 的策略主干；任务/阶段 token 直接进入对话状态 | 不改单 checkpoint/单 API |
| IP-02 GraspVerify | 抓握/接触信号作为 `b_t` 的一个观测源；`MUST` 阶段的接触确认 | 不改其“高精度低召回”介入原则 |
| IP-03 ChunkStitch | 短 chunk 边界继续用一阶外推 + 残差；RiskChunk 只改长度 | 不改缝合器的 C0/C1 语义 |
| IP-06 SimBench | 六因子分解作为 `Φ_t` 的阶段信号与失败归因 | 不改其代理评测口径 |
| IP-08 AuditLayer | 与 DialogLedger 合并：延迟/jerk/对话回合统一导出 | 不改官方可信度口径 |

**关键**：本线**不新增接口字段**，不改变 `metadata / get_action / reset` 三件套；所有安全对话都在服务内部完成。对外仍然是一个策略、一个 checkpoint、一个 API。

## 12. 本轮最值得押注的创新点（一句话）

**押注 IP-SD2 + IP-SD3 的组合：把“避障控制”从“全接触禁令”改成“接触语义 + 机会约束”，再把“对话管理”从聊天系统搬成“策略 / 安全 / 感知之间的有界协商”——pilot 已显示它能把窄通道成功率从 48% 提到 66.5%、把非目标碰撞从 1.5% 压到 0%，而这两件事恰好是 UniBot 桌面任务“最后一环”最需要的。**

**本轮最大风险（一句话）**：整套安全性押在目标/干扰物/支撑面/人的语义分类上，而未见物品与人为干扰正是分类最不可靠的场景——分类错一次，安全层就会把该抓的当该躲的（锁死）或把该躲的当该抓的（碰撞），对话只能放大而不能纠正这个错误。
