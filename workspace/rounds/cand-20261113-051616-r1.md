# 第 1 轮（新灵感循环 v5：「情感计算」×「桌面操作」）—— 给桌面策略装一套「能动感」：先分清「我失败了」还是「人把我改了」

> 承接 v2（UIP-01′~15）。v2 已经找到最大得分缺口：`human_*` 的反向撤回。但 v2 的验证器只回答「这一步现在成立不成立」，不回答「为什么变成这样」。同样是「拉链开了」，可能是机器人根本没拉上（自失败）、拉上后被人拉开（外部撤回）、拉链头被挪歪（位移）、或包被拿走（移除）。四者的正确反应完全不同：重抓、重做、重对齐、止损。把四者混成一个 `regressed`，就会「用正确的力度做错误的恢复」。本轮两个灵感词正好补这个缺口：**情感计算**提供一套低维状态（效价/唤醒/支配）与「能动感（sense of agency）」的计算框架；**桌面操作**提供一个对象有限、可逆、受重力约束的小闭世界，使「动作—对象—谓词」的前向模型可算。主线：**用机器人自己的「能动感」把回归拆成原因，再用情感状态调度恢复；人的情感只作为可选的前兆，不作为主信号。**

---

## 0. 先给直觉：三个桌面场景，为什么静态验证器会「误诊」

- **T19 拉链**：机器人把拉链拉上（该步计分），人随后快速拉开。下一次 `get_action` 只看到「拉链是开的」。静态谓词能说「这一步没成立」，但分不清：①机器人根本没拉上；②拉上了又被人拉开；③拉链头被挪歪。三者的恢复动作不同——①要重抓/重对齿，②要重做拉上，③要重对齐后再拉。若把三者都当①，就会在「人已经拉开」时反复重抓；若都当②，就会在「根本没拉上」时反复空拉。
- **T12 开锁**：机器人开到一半，人把锁整个拿走。正确反应不是「重做开锁」，而是**止损/搜索**。静态验证器只会说「锁没开」，策略可能对着空气重试到超时。
- **T27 叠碗**：机器人叠好第二个碗，人把第二个拿下来。第一个碗还在、第二个碗不见了。正确反应是**只重做第二个**，而不是从头叠。静态验证器看到「叠碗谓词不成立」，无法区分「第一个没叠好」与「第二个被拿走」。

三者的共同结构是：**末态观测可以完全相同，但成因（自身失败 / 外部撤回 / 外部位移 / 对象移除）不同；真正的判别信号是「动作与状态变化之间的因果关系」，而不是某一帧的谓词。** 机器人唯一稳定拥有的因果证据，是它自己刚下发的动作块 `A_t` 与执行后的状态变化 `Δs_t`：如果 `Δs_t` 能被 `A_t` 解释，就是自身作用；如果解释不了，就是外部作用。这个「动作—感觉后果」的比较，正是认知科学里的**比较器模型（comparator model）**，也是**能动感（sense of agency, SoA）**的计算基础。

**情感计算的直觉**：情感计算不只是「读人脸」。Picard 的定义是「与情感或其他情感现象相关、由之产生、或有意影响情感的计算」（Picard, 1997；综述见 https://par.nsf.gov/servlets/purl/10331619 ）。在机器人身上，最有用的不是给它贴「开心/难过」，而是把**评价变量**压成一个低维状态：**效价（valence）= 任务进度好不好；唤醒（arousal）= 意外/预测误差有多大；支配（dominance）= 我对结果还有多少控制感**。这三者恰好是恢复决策需要的三个问题：还要不要继续？要不要先核验？该重做还是该让行？**情感状态不是装饰，而是开环动作块约束下的「决策充分统计量」。**

**桌面操作的直觉**：桌面是一个「小闭世界」：物体有限、都在支撑平面上、受重力约束、不会凭空消失；操作是可逆的（开/合、拉上/拉开、叠上/拿下、放入/取出）。因此我们不需要通用世界模型，只需要一个**对象中心的前向模型**：给定机器人动作，预测每个对象槽的位姿与谓词；预测不了的残差，就是外部扰动。头部双目还提供公制深度，可把桌面重建为 2.5D 高度图，使「对象在不在、在哪、叠了几层、盖子开了多少」可算。**桌面结构让「能动感」从哲学概念变成一个可计算的残差。**

## 1. 为什么是「情感计算」，而不是「再加一个验证器」

### 1.1 情感计算的三维核心状态，正好对应恢复决策的三问

情感计算的主流维度模型是 **PAD（Pleasure-Arousal-Dominance）**，其二维特例是 Russell 的 **Valence-Arousal** 环状模型。我们不做情绪分类，而是把 PAD 当作**评价空间**：

| 维度 | 机器人上的可观测映射 | 在恢复决策中的作用 |
|---|---|---|
| **效价 V** | 计分步进度 `S_t/100`、子目标完成度 | 低 V = 进度受损，需要恢复/重做 |
| **唤醒 Ar** | 动作条件前向模型的残差、谓词翻转的意外度 | 高 Ar = 有外部事件或模型失配，需要先核验 |
| **支配 D** | 能动感 `α_t`（状态变化被自身动作解释的概率） | 低 D = 外部作用，需让行/止损；高 D = 自身作用，需重抓/重试 |

这不是把机器人「拟人化」，而是把**评价理论（appraisal theory）**里的三个量（目标一致性、意外/强度、应对潜力）落到可观测信号上。它带来的直接好处是：**恢复不再是「检测到 regressed 就重做」，而是「先归因，再选恢复模式」**。这也是本轮与「面部表情识别」路线的区别：FER 读人，SALT 读机器人自己的动作—感觉回路；前者依赖人脸可见，后者在无人时也成立。

### 1.2 能动感（SoA）是「因果归因」的现成计算框架

SoA 的核心是比较器模型：大脑/系统比较「动作的预测后果」与「实际感觉后果」，匹配度高 → 感觉「这是我做的」；匹配度低 → 归因于外部。机器人版本更简单：

```
预测：\hat{s}_{t+1} = f_θ(s_t, A_t)
残差：r_t = s_{t+1} - \hat{s}_{t+1}
能动感：α_t = P(self | r_t, A_t)
```

`α_t` 低不一定就是人干的：也可能是模型错了、接触没建上、物体滑了。因此 SoA 必须带**校准的不确定性**，并且只在「残差显著且方向与谓词变化一致」时才归因于外部。这一点是本轮与 v2 最重要的区别：**v2 把「没做到」当事实；本轮把「没做到」当假设，并显式比较「自身失败 / 外部撤回 / 外部位移 / 对象移除」四种解释。**

### 1.3 人的情感是可选前兆，不是主信号

人的不耐烦/紧迫/投入会影响他何时伸手。若头部相机能看到人的手、身体前倾、接近速度、停顿节奏，就可以估计一个**干预风险** `λ_t`，让机器人提前让行或加速完成。但这条链路有三个硬前提：①人必须在画面里且可观测；②人的干预必须与情感/行为前兆相关；③规则允许使用人体检测。三者都未核实。因此本轮把它放在**条件分支**：主回路只依赖机器人自己的 SoA，人的情感只作为「有则更好」的前兆。这样即使评测时没有真人、或人脸不可见，SALT 仍然成立。

## 2. 严谨定义

### 2.1 观测与动作

一次 episode 的观测

```
o_t = (I_t^{hl}, I_t^{hr}, I_t^{wl}, I_t^{wr}, q_t, e_t, g_t, l)
```

其中 `I^{hl/hr}` 为头部左右 RGB，`I^{wl/wr}` 为腕部 RGB，`q_t` 为关节位置（含左右臂与 `lower_body`），`e_t` 为左右末端位姿，`g_t` 为夹爪开合，`l` 为语言指令。动作块 `A_t = (a_{t,1},...,a_{t,T_a})`，`T_a` 在 metadata 握手时固定；评测端整块执行后才再次调用。**没有力/触觉，没有人类状态，没有显式深度**（头部双目可离线/在线恢复深度）。

### 2.2 桌面状态

```
s_t = (X_t, P_t, W_t)
```

- `X_t = {x_i}`：对象槽，`x_i = (class, pose, shape, support, graspable)`；
- `P_t`：谓词集合，如 `on(o,s)`、`in(o,c)`、`stacked(a,b)`、`open(c,θ)`、`inserted(p,port,d)`、`zipped(z,f)`、`folded(t,f)`、`sorted(o,bin)`、`upright(o)`、`clear(region)`；
- `W_t`：见证集合，`w = (predicate, t, value, confidence, source)`，`source ∈ {stereo, wrist, proprio, model}`。

计分链 `G = (g_1..g_n)`，权重 `w_i`，`Σw_i=100`；每个 `g_i` 对应一个目标谓词（或合取）。

### 2.3 对象中心前向模型

```
f_θ: (s_t, A_t) ↦ \hat{s}_{t+1}, Σ_t
```

分解为三部分：

1. **机器人运动学**：由 `A_t` 与当前关节/末端状态预测下一时刻的末端位姿与夹爪状态；
2. **对象动力学**：对每个被操作对象，预测其在接触/重力/支撑下的位姿变化；接触模式（抓牢/滑动/未接触）是隐变量；
3. **谓词投影**：`\hat{P}_{t+1} = Pred(\hat{s}_{t+1})`。

`Σ_t` 是校准的预测协方差，来自异方差头或小集成。桌面任务的特殊性在于：大部分对象是刚体、支撑平面已知、动作是准静态的，因此前向模型可以很轻；接触密集步（插入/拧盖/拉链）误差大，`Σ_t` 必须相应变大。

### 2.4 能动感（SoA）

对每个任务相关对象 `i`，定义残差与能动感：

```
r_{i,t} = x_{i,t+1} - \hat{x}_{i,t+1}
α_{i,t} = P(self | r_{i,t}, A_t)
        = σ( log p(r_{i,t} | self, A_t) - log p(r_{i,t} | ext) )
```

若自身假设下 `r_{i,t} ~ N(0, Σ_{i,t})`，外部假设下为宽分布，则

```
α_{i,t} = exp(-½ r_{i,t}^T Σ_{i,t}^{-1} r_{i,t}) / Z
```

聚合 `α_t = min_i α_{i,t}`（最不可解释的对象决定整体能动感）。同时记录**符号化残差** `r^-_{i,t}`：若残差方向与某个已完成谓词的反向一致（如拉链从 closed 变 open、碗从 stacked 变 unstacked），则外部撤回的似然上升。

### 2.5 情感状态与「情绪」

```
z_t = (V_t, Ar_t, D_t)
V_t = \hat{S}_t / 100                    # 效价：进度
Ar_t = 1 - α_t                           # 唤醒：不可解释的意外
D_t = α_t                                # 支配：能动感
m_t = (1-η) m_{t-1} + η z_t              # 情绪：慢变量，η∈(0,1)
```

`m_t` 是跨块的情感记忆，用来防止「单帧误判导致反复横跳」：一次低能动感不应立刻让机器人惊慌；连续多次低能动感才应升级为「外部干扰模式」。这相当于给恢复策略加了一个**低通滤波器**。

### 2.6 因果归因

定义原因假设集合

```
H = {self, undo, displace, remove, obstruct, supply, unknown}
```

对每个假设定义似然：

- `self`：`r_t` 小（动作能解释），但谓词没有推进（动作无效/滑脱）；
- `undo`：`r_t` 大，且方向与某个已完成谓词的反向一致，动作幅度小（机器人没在主动反向）；
- `displace`：`r_t` 有横向/侧向分量，谓词可能仍成立，但对象位姿改变；
- `remove`：对象槽消失或置信度骤降；
- `obstruct`：人手/人臂占据工作区，动作被阻挡，对象未移动；
- `supply`：出现新对象，或人完成了某个前置步骤；
- `unknown`：以上都不显著，或 `Σ_t` 太大。

后验：

```
P(H | o_{1:t}, A_{1:t}) ∝ P(H) Π_τ p(o_τ | H, A_τ)
```

实现上不需要重型贝叶斯网络：用规则化的似然 + 一个轻量分类头即可；关键是**输入必须包含动作 `A_t`**，否则无法区分「自失败」与「外部撤回」。

### 2.7 情感条件化恢复

恢复不是单一动作，而是一个带安全块尾的有限状态机：

| 归因 | 恢复模式 | 具体动作 | 安全块尾 |
|---|---|---|---|
| `self` | `REGRASP` | 张开/闭合夹爪、重新接近、重抓 | 退到抓取前 5 cm 的安全位 |
| `undo` | `REDO` | 重做被反向的计分步 | 完成动作后保持/轻抬，等待核验 |
| `displace` | `REALIGN` | 重新定位对象、调整抓取、继续 | 退到对象上方 5 cm |
| `remove` | `SEEK/ABORT` | 扫描工作区；找不到则优雅终止 | 收臂到中立位 |
| `obstruct` | `YIELD` | 后退、等待、让人手离开 | 保持静止、夹爪张开 |
| `supply` | `INTEGRATE` | 核验新对象/新状态，更新账本 | 轻抬/展示后继续 |

每个模式生成的块，最后 `k` 步必须是**安全保持/回撤**形态，使下一个块边界发现新证据时机器人仍在可恢复姿态。这是对「开环块 + 固定 `T_a`」约束的直接回应：既然不能在块内反应，就把「可反应性」设计进块尾。

### 2.8 可选：人的干预风险与可读性信号

若人类在画面中，定义干预风险

```
λ_t = lim_{Δ↓0} P(N(t+Δ)-N(t)=1 | F_t)/Δ
```

用 Cox/逻辑回归或轻量时序头估计，特征 `e_t` 包括：人手接近速度、到当前操作对象的距离、身体前倾、视线方向（若可见）、距上次进度的时间、重复失败次数。机器人可用**动作**（唯一输出通道）发出可读信号：

- `COMMIT`：完成高价值步后轻抬对象 2 cm、停顿 0.3 s，再放下——表达「这步已经完成」；
- `YIELD`：后退 10 cm、张开夹爪、停顿——表达「你可以接手」；
- `HESITATE`：小幅来回 + 头部转向——表达「我在犹豫」（慎用，可能招致干预）；
- `PRESENT`：把对象移到人视野中央——表达「看，做好了」。

这些不是「卖萌」，而是**用运动降低人误判进度的概率**。它们的效果必须在人机实验中检验；若评测是脚本化干扰，`λ_t` 与 `LPS` 自动降级为无效分支。

### 2.9 目标

```
max_π  E[ Σ_i w_i b_T(g_i) - c_int N_int - c_safe 1[collision] - c_time T ]
```

其中 `b_T(g_i)` 是 episode 结束时计分步完成的信念，`N_int` 是干预次数，`c_safe` 是安全惩罚，`c_time` 是时间/延迟惩罚。SALT 不直接优化这个 POMDP（不可解），而是用「归因 → 模式 → 安全块」的阈值策略近似它。

## 3. 与 v2 的关系：升级、合并、修剪

- **升级 UIP-01′ → UIP-01‴（RHPV-D + SoA）**：`regressed` 不再是一个布尔量，而是 `H` 上的后验；验证器从「谓词裁判」升级为「因果裁判」。
- **合并 UIP-09′ → UIP-18 ACR**：原「检测撤回→重做」并入「按原因选择恢复模式」，不再单列。
- **修正 UIP-13′（ACS-2）**：`T_a` 握手后固定，运行期不能变长；原「自适应块长」不成立。改为「固定 `T_a` + 块尾安全形态 + 计算调度」。
- **保留 UIP-11″ TGO（Isaac 几何/接触顾问）**：用于离线生成带标签的扰动、校准前向模型与 SoA 阈值；但不把仿真当成败裁判。
- **保留 UIP-12′ UOF（撤回算子工厂）**：`human_*` 的撤回可编译成逆算子，用于生成 `(完成→撤回→恢复)` 数据。
- **保留 UIP-14 MSGR、UIP-15′ CSG、UIP-08′ LAT-ENG、UIP-02′ SSG、UIP-05 LCAG**。
- **新增 UIP-16 SoA、UIP-17 AAS、UIP-18 ACR、UIP-19 LPS、UIP-20 HAH**（定义见产物区）。
- **修剪**：不引入独立的大情感模型；不做人脸依赖；不增加力/触觉假设；不运行期切换 joint/ee；不声称毫秒级块内反应。

**四条必须先做的审计**（否则就是拿未经验证的因果链讲故事）：

- **A0（SoA 信号存在）**：在 5 个代表任务上，动作条件残差能否把「自失败」与「外部撤回」分开？若 AUC < 0.7，SALT 降级为「只做核验，不做归因」。
- **A1（前向模型可校准）**：接触密集步的 `Σ_t` 是否能覆盖真实误差？若 ECE > 0.1，归因不可信，必须回退到几何验证器。
- **A2（人的情感有前兆）**：人手进入/身体前倾/停顿对 2 秒内干预的预测力是否显著高于随机？若不显著，删除 HAH/LPS 在线分支，只保留离线分析。
- **A3（合规）**：是否允许人体检测、外部预训练、合成数据？若不允许，全部蒸馏进共享骨干或用纯几何线索。

## 5. 瓶颈假设

- **H1（最高杠杆）**：在桌面任务里，动作条件残差 `r_t` 能把「自失败」与「外部撤回」分开；因为前者是「有动作、无位移」，后者是「无动作、有位移」。这是比静态谓词更强的因果信号。
- **H2**：按原因选择恢复模式，比统一「重做」更能保住步骤分；尤其是 `remove`（止损）与 `displace`（重对齐）两类，统一重做会浪费大量时间。
- **H3**：情感状态 `(V,Ar,D)` 的低通/情绪 `m_t` 能抑制「单帧误判 → 反复横跳」，降低无效重试。
- **H4**：人的情感/行为前兆只有在「人响应机器人行为」时才有用；脚本化干扰下应自动降级。
- **H5**：SoA/AAS 作为共享骨干上的轻量头或纯几何计算，延迟 <5 ms，不破坏可信度。

## 6. 候选与合并 → SALT

围绕两个词发散 9 个草案，合并为 5 个新 UIP + 1 个旗舰：

- **UIP-16 SoA**：能动感估计器（动作条件前向模型 + 残差 + 校准不确定性）。
- **UIP-17 AAS**：情感状态向量（V/Ar/D + 情绪低通）。
- **UIP-18 ACR**：情感条件化恢复（按原因选模式 + 安全块尾）。
- **UIP-19 LPS**：可读进度信号（COMMIT/YIELD/HESITATE/PRESENT）。
- **UIP-20 HAH**：人的干预风险（身体/手部前兆，条件启用）。
- **旗舰 SALT** = UIP-16 + UIP-17 + UIP-18；UIP-19/20 为条件分支。

**与 v2 的差异一句话**：v2 问「这一步成了吗」；SALT 问「这一步为什么没成，是谁弄的，我该重做、重抓、重对齐，还是止损」。前者是**状态验证**，后者是**因果验证 + 情感调度**。

## 7. 本轮最大风险

**一句话**：如果桌面接触密集步的前向模型误差没有被校准，SoA 会把「我自己没抓稳」误判成「人把我改了」，于是机器人用错误的恢复模式（让行/止损）替代正确的重抓，情感层就从「因果证据」退化成「甩锅引擎」；必须以校准不确定性、`unknown` 回退和几何验证器兜底，且只在 `P(H) > τ` 时才允许改变恢复模式。

**四段闭环**：

1. **感知段**：把 4 路 RGB + 本体状态变成对象槽、谓词与见证；头部双目提供公制 2.5D，腕部提供接触近景。
2. **归因段**：用动作条件前向模型算残差，得到 SoA 与原因后验；这是本轮的核心新增。
3. **情感段**：把进度、意外、能动感压成 V/Ar/D，并用情绪低通抑制单帧误判；情感状态决定「先核验还是直接恢复」「恢复多快」「要不要让行」。
4. **执行段**：按原因选恢复模式；每个块的最后 `k` 步是安全保持/回撤，保证下一个块边界可切换。

## 2. 关键算法

### 2.1 SoA 与归因

```python
def sense_of_agency(s_t, A_t, s_next, Sigma_t, pi_ext=0.3):
    """UIP-16: 动作条件残差 → 自身/外部后验。"""
    s_hat = forward_model(s_t, A_t)          # 机器人运动学 + 对象动力学 + 谓词投影
    r = residual(s_next, s_hat)              # 对象槽/末端位姿残差
    # 自身假设：r ~ N(0, Sigma_t)；外部假设：宽分布（用混合/均匀近似）
    log_self = log(1 - pi_ext) - 0.5 * mahalanobis(r, Sigma_t) - 0.5 * logdet(Sigma_t)
    log_ext  = log(pi_ext)     - 0.5 * (r / sigma_ext).pow(2).sum()
    alpha = sigmoid(log_self - log_ext)      # 能动感
    return alpha, r, s_hat

def attribute(s_t, A_t, s_next, Sigma_t, pred_prev, pred_next):
    """UIP-01‴: 原因后验（规则化似然 + 轻量头）。"""
    alpha, r, s_hat = sense_of_agency(s_t, A_t, s_next, Sigma_t)
    H = {}
    # 1) 自失败：动作幅度大、对象几乎没动、谓词未推进
    H["self"] = lik_self(r, A_t, pred_prev, pred_next)
    # 2) 外部撤回：动作幅度小、残差方向与已完成谓词反向一致
    H["undo"] = lik_undo(r, A_t, pred_prev, pred_next)
    # 3) 外部位移：横向残差大、谓词可能仍成立
    H["displace"] = lik_displace(r, pred_prev, pred_next)
    # 4) 移除：对象槽消失/置信度骤降
    H["remove"] = lik_remove(s_next)
    # 5) 阻挡/补料：人手/新对象
    H["obstruct"] = lik_obstruct(s_next)
    H["supply"] = lik_supply(s_next)
    # 6) 不确定：Sigma 太大或所有似然都低
    H["unknown"] = lik_unknown(Sigma_t, H)
    return normalize(H)
```

### 2.2 情感状态与情绪

```python
def affect_update(progress_hat, alpha, m_prev, eta=0.3):
    """UIP-17: V/Ar/D + 情绪低通。"""
    V = clamp(progress_hat / 100.0, 0, 1)   # 效价：进度
    Ar = clamp(1.0 - alpha, 0, 1)           # 唤醒：不可解释的意外
    D = clamp(alpha, 0, 1)                  # 支配：能动感
    z = (V, Ar, D)
    m = tuple((1 - eta) * mp + eta * zp for mp, zp in zip(m_prev, z))
    return z, m
```

### 2.3 情感条件化恢复

```python
def choose_mode(H, z, m, verifier_conf, cfg):
    """UIP-18: 归因 + 情感 + 置信度 → 恢复模式。"""
    h = argmax(H)
    if H["unknown"] > cfg.tau_unknown or verifier_conf < cfg.conf_floor:
        return "VERIFY"                      # 不归因，回退几何验证器
    if h == "self":
        return "REGRASP" if m[0] < cfg.v_low else "VERIFY"
    if h == "undo":
        return "REDO"
    if h == "displace":
        return "REALIGN"
    if h == "remove":
        return "SEEK" if cfg.allow_search else "ABORT"
    if h == "obstruct":
        return "YIELD"
    if h == "supply":
        return "INTEGRATE"
    return "VERIFY"
```

### 2.4 固定块长 + 安全块尾

```python
class SALT_Policy:
    def __init__(self, base, forward_model, verifier, T_a, cfg):
        self.base = base
        self.f = forward_model
        self.v = verifier
        self.T_a = T_a                  # 握手时固定，运行期不变
        self.cfg = cfg
        self.m = (0.5, 0.5, 0.5)        # 情绪初值

    def reset(self):
        self.base.reset()
        self.m = (0.5, 0.5, 0.5)
        self.H_prev = None
        self.s_prev = None
        self.A_prev = None

    def get_action(self, obs):
        s = self.perceive(obs)                    # 对象槽/谓词/见证
        # 1) 用上一块的动作与当前状态做归因
        if self.s_prev is not None:
            Sigma = self.f.sigma(self.s_prev, self.A_prev)
            alpha, r, s_hat = sense_of_agency(
                self.s_prev, self.A_prev, s, Sigma)
            H = attribute(self.s_prev, self.A_prev, s, Sigma,
                          self.s_prev.P, s.P)
        else:
            alpha, H = 1.0, {"unknown": 1.0}
        # 2) 情感更新
        z, self.m = affect_update(self.v.progress(s), alpha, self.m)
        # 3) 选模式
        mode = choose_mode(H, z, self.m, self.v.confidence(s), self.cfg)
        # 4) 生成整块，并强制安全块尾
        A = self.base.get_action(obs, mode=mode)   # 必须返回 (T_a, d)
        A = self.safe_tail(A, mode)                # 最后 k 步保持/回撤
        # 5) 记录本块，供下一次归因
        self.s_prev, self.A_prev = s, A
        return A

    def safe_tail(self, A, mode):
        """最后 k 步替换为安全保持/回撤，保证块边界可切换。"""
        k = self.cfg.k_tail
        if mode in ("REGRASP", "REALIGN"):
            A[-k:] = self.hold_or_retreat(A[-k], distance=self.cfg.retreat_cm)
        elif mode in ("REDO", "INTEGRATE"):
            A[-k:] = self.hold_or_lift(A[-k], height=self.cfg.lift_cm)
        elif mode == "YIELD":
            A[-k:] = self.retreat_and_open()
        return A
```

**注意**：`get_action` 返回的是完整 `(T_a, d)` 块，不是单步；`T_a` 不在运行期改变。v2 伪代码里的 `return self.buf.pop(0)` 形状不符，本轮已修正。

## 3. 桌面对象中心前向模型（UIP-16 的底座）

### 3.1 2.5D 桌面重建

头部双目校正后，视差 `d` 与深度 `Z = fB/d`，误差传播

```
σ_Z = Z²/(fB) · σ_d
```

官方标定 `B≈60.11 mm`、`f≈272 px`：0.5 m 处 `σ_d=1 px` → `σ_Z≈15 mm`。把点云变换到桌面坐标系（支撑平面拟合 + 重力方向），栅格化为高度图 `HM(x,y)`；连通域得到对象槽 `X_t`；时间一致性维护谓词与见证。15 mm 足以支撑 `on/in/stacked/open/clear` 等粗谓词，但不足以支撑 `inserted(d)` 的毫米级深度——后者交给腕部近景 + 本体夹爪/关节。

### 3.2 对象动力学

对每个被操作对象 `i`：

```
x_{i,t+1} = x_{i,t} + Δx_i(A_t, c_i) + ε_i
c_i ∈ {grasped, sliding, free, supported, inserted}
```

- `grasped`：对象随末端刚性运动，`Δx_i ≈ Δe_t`；
- `sliding`：接触但未抓牢，`Δx_i` 由摩擦/接触力近似；
- `free`：重力/支撑，`Δx_i` 由桌面高度图与重力方向预测；
- `inserted`：受孔/槽约束，`Δx_i` 投影到插入轴。

`ε_i ~ N(0, Σ_i)`，`Σ_i` 由离线标定 + 异方差头给出。接触密集步（插入/拧盖/拉链/折叠）的 `Σ_i` 自动放大；**`Σ_i` 大时 SoA 自动降低，归因回退到 `unknown`**，避免「模型不准还硬甩锅」。

### 3.3 谓词与见证

```
P_t = { on(o,s), in(o,c), stacked(a,b), open(c,θ), inserted(p,port,d),
        zipped(z,f), folded(t,f), sorted(o,bin), upright(o), clear(region) }
```

每个谓词带见证 `(value, confidence, source)`。只有 `confidence ≥ τ_p` 的谓词才允许写入真实账本；低于阈值时降级到腕部/本体见证，或增加核验频率。

## 4. 玩具机制实验（不是机器人实验）

> 目的：只验证「动作条件残差能否把 self 与 undo 分开」这一条逻辑。绝对分数依赖假设的恢复成功表，不能当作真机结论。
> 脚本：`exp/salt_sim.py`；结果：`exp/salt_results.json`。

### 4.1 设置

- 原因先验：`self 0.35 / undo 0.30 / displace 0.20 / remove 0.15`。
- 观测特征：`a`（本块命令位移）、`dx`（观测位移）、`dy`（侧向位移）、`present`（对象是否存在）。
- 生成模型：
  - `self`：`a∈[0.10,0.30]`，`dx≈N(0,σ)`（有动作、无位移）；
  - `undo`：`a∈[0,0.05]`，`dx≈N(-1.0,σ)`（无动作、有反向位移）；
  - `displace`：`a∈[0,0.05]`，`dy≈N(0.5,σ)`；
  - `remove`：`present=0`。
- 静态验证器（v2 风格）：只看 `dx/dy/present`，对象在就一律 `redo`，对象不在就 `abort`。
- SALT 归因：先看 `present`，再看 `|dy|`，再看 `a` 与 `|dx|`。
- 恢复成功表（示例假设）：self→regrasp 0.85 / redo 0.45；undo→redo 0.90 / regrasp 0.55；displace→realign 0.85 / redo 0.40；remove→search 0.50 / redo 0.00。恢复成功则得 `50 + 50×0.8 = 90` 分。

|---:|---:|---:|---:|

| 0.03 | 1.000 | 45.7 | **73.1** |

**读法**：

1. 静态验证器不是「不够聪明」，而是**输入里没有动作**；它天然无法区分 self 与 undo。
2. SALT 的增益来自「用动作解释残差」：`self` 是「有动作、无位移」，`undo` 是「无动作、有反向位移」。
3. 噪声大时，`self` 会被误判为 `displace`（侧向噪声超过阈值）或 `undo`；这正是需要**校准 `Σ_t` + 滞后/情绪低通**的地方。高噪声下准确率从 1.000 掉到 0.956，期望分从 73.1 掉到 71.2，说明机制不是「完美但脆弱」，而是「有明确失效边界」。

### 4.3 决策论增益（可手算的部分）

设原因先验 `P(c)`，统一重做的成功率 `s(c,redo)`，归因后的成功率 `s(c,a*(c))`，恢复成功得 `S=90`：

```
E[S_static] = 90 · Σ_c P(c) · s(c,redo)
E[S_SALT]   = 90 · Σ_c P(c) · s(c,a*(c))
Δ           = 90 · Σ_c P(c) · [s(c,a*(c)) - s(c,redo)]
```

代入上面的表：`E[S_static]=45.7`，`E[S_SALT]=73.1`，`Δ=27.4` 分。这个数不是真机结果，但它说明**归因错误不是「小误差」，而是直接决定恢复动作对不对**。

## 5. 全尺寸实验设计

### 5.1 任务与扰动

- **5 个代表任务**：T12 开锁（移除）、T14 倒药（拧回）、T16 叠毛巾（翻开）、T19 拉链（拉开）、T27 叠碗（拿下第二个）；外加 T26 插网线（接触密集，测前向模型误差）。
- **扰动生成**：
  1. **Isaac/TGO**：程序化生成 `self`（滑脱/未抓牢）、`undo`、`displace`、`remove`、`obstruct`、`supply` 六类，带真值标签；
  2. **UOF**：把 `human_*` 文本编译成逆算子，生成 `(完成→撤回→恢复)` 三元组；
  3. **真机**：脚本化机械手/人手动扰动，至少覆盖 5 任务 × 4 原因 × 40 次。
- **训练/测试划分**：按任务/对象/背景划分，避免同一 episode 泄漏。

### 5.3 人机实验（E305）协议

- **被试**：20 人（组内设计），随机顺序；知情同意；不采集/存储人脸原图，只存匿名化关键点。
- **条件**：A=无 LPS；B=有 LPS（COMMIT/YIELD）；C=脚本化干扰（不响应机器人）。
- **任务**：T19 拉链、T27 叠碗、T12 开锁。
- **指标**：干预次数/分钟、首次干预时延、任务完成时间、碰撞/逼近次数、信任量表、舒适度量表。
- **假设检验**：若 B 相对 A 的干预率下降不显著，或 C 条件下无差异，则 LPS 只保留为离线分析，不进在线策略。

### 5.4 统计与可复现

- 每个条件 ≥200 episodes；报告 bootstrap 95% CI；归因指标用 macro-F1（类别不平衡）；恢复指标用步骤分与成功率。

## 7. 本轮最大风险与押注

**一句话**：SALT 的命门不是「情感状态够不够像人」，而是「前向模型在接触密集步够不够准」；一旦 `Σ_t` 被低估，SoA 会把自失败误判成外部撤回，机器人就会在「该重抓」时选择「让行/止损」，把因果层变成甩锅层。

**→ 本轮最值得押注**：**UIP-16 SoA + UIP-18 ACR 的「归因-恢复」闭环**，先在 5 个代表任务上把「self vs undo vs displace vs remove」四分类做到 macro-F1 ≥ 0.8、恢复步骤分相对 v2 统一重做 +15% 以上；UIP-17 情感状态只作为调度器，UIP-19/20 人的情感只作为条件分支。这个押注精确对准 v2 的最大盲区——**不是「没检测到撤回」，而是「检测到了却不知道为什么」**——且完全落在选手 API 权限与离线算力之内。
