# 第 13 轮（新循环第 1 轮）· DART-SERVO：把 CHUNK-SERVO 的「固定 5 步」做成「截止时间感知的嵌入式实时伺服」

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新灵感循环第 1 轮，研究线承接第 10 轮 **FACT-VLA**、第 11 轮 **GEO-RESIDUAL**、第 12 轮 **CHUNK-SERVO**。三个灵感词是「仿真训练」「视觉语言动作模型」「嵌入式系统」。本轮不推倒 CHUNK-SERVO 的「30 步规划 + 5 步伺服」，而是补它默认掉的一层：**伺服不只需要算得准，还需要在截止时间内算完；算不完时，要按一个可审计的顺序优雅退化；异步 VLA 的计划要按时间而不是按索引执行。**

## 0. 先给结论：CHUNK-SERVO 缺的不是控制律，是「控制律的执行契约」

第 12 轮把反馈周期从 1 秒压到 167ms 执行块（含 RTT 约 200–320ms），方向是对的。但它有三个没有被写进公式的假设：

1. **伺服计算时间可忽略。** 实际上 `get_action` 里要做图像解码、ROI、双目匹配、PBVS/IBVS、检索重排、msgpack 序列化；在 Python 服务里，这些成本会随图像尺寸、N 端口并发、GC 和 CPU 频率漂移。如果一次 `get_action` 自己花 80–150ms，端到端反馈周期会回到 250–370ms，而且 p99 抖动会让评测端记录的“动作统计规律”变差。
2. **异步 VLA 的 plan 可以按固定索引切片。** 但 VLA 推理是异步的：plan 可能在请求后 30ms 返回，也可能 300ms 后才返回。若还在用旧 plan 的第 0 步，就等于用 300ms 前的世界执行现在的动作；若把相对动作重新 compose 到当前 EE，又会把“已经走过的位移”再加一遍。
3. **仿真只用于标定，不参与控制器参数设计。** 第 12 轮把数字孪生限定为“相机外参/增益/RTT 的风洞”。这避开了 sim-to-real 策略训练的风险，但也浪费了仿真最擅长的事：在大量延迟、抖动、遮挡、CPU 负载的组合下，**离线搜索一张可审计的控制器参数表**。

所以本轮的押注是 **DART-SERVO**（Deadline-Aware Real-Time Servo）：

> **把每端口 PolicyService 做成一个有 WCET 预算的软实时流水线；每次 `get_action` 在剩余预算内选择“价值最高且能按时完成的伺服阶段”，永远返回当前最优的合法动作；用仿真离线训练一张“上下文 → 阶段子集/增益/死区”的查找表；用时间重锚定修正异步 VLA 的 stale plan；用一个截止时间感知的前馈降速器保证开环漂移不超过任务容差。VLA 仍是唯一学习模型，伺服仍是确定性控制器，查找表不是第二个模型。**

一句话对比上一轮：**第 12 轮让最后 3 厘米“有闭环”；本轮让这个闭环“在 30Hz 远程 API 的截止时间内真的闭合，并在算不完时退化得可预测”。**

三个可验证创新点：

1. **RT-Contract + ASL（实时契约 + anytime 伺服阶梯）**：把 S0 计划重锚定、S1 PBVS、S2 头部双目、S3 腕部 IBVS、S4 检索重排拆成有 WCET 的阶段；每次调用在 `D_r` 内选择可行子集，执行到预算耗尽即停，返回 best-so-far。验证：G1/G5/G6。
2. **STSM（Sim-Trained Schedule Map，仿真训练调度表）**：在数字孪生里对 64 个上下文桶 × 128 个候选配置做 rollout，按成功率、稳态误差、计算成本、deadline miss 选 Pareto 点；用 ±30% 时间扰动和遮挡扰动做鲁棒认证。验证：G2/G3。
3. **TPR + DASD（时间重锚定 + 截止时间感知降速）**：plan 在生成时一次性 compose 成 base 系绝对目标，执行时按 plan age 重索引；目标移动用一阶预测补偿；若 `T_fb` 超过相位截止时间，按 `γ = e_φ/(v T_fb)` 缩放前馈速度。验证：G4/G7。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **仿真训练** | 离线训练 STSM：64 个上下文桶、16 个阶段子集、4 档增益、2 档死区；在 IsaacLab/MuJoCo 里注入 RTT/抖动/遮挡/CPU 负载；只用仿真选控制器参数，不训 VLA 权重 | 不在仿真里从零训 6B VLA；不用仿真成功率预测真机绝对成功率；不把查找表说成“策略网络” |
| **视觉语言动作模型** | VLA 仍负责 30 步语义规划；TPR 记录 plan 的锚点时刻/锚点 EE 位姿，预 compose 成绝对目标，按 plan age 重索引；plan 过期就丢弃，不在旧计划上硬追 | 不加载第二个模型；不做残差学习；不把 VLA 多次采样当集成模型（本轮不碰这条） |
| **嵌入式系统** | 每端口固定周期、预分配内存池、无锁 SPSC、C++/pybind11 热路径、看门狗、降级阶梯、CPU 亲和性、N 端口 EDF GPU 队列、WCET 实测 | 不改 G1 固件；不假设硬实时 OS；不假设 API 有 timestamp/IMU；不做 30Hz 广域网全图伺服 |

## 1. 直觉：三个词其实是一条「时间—参数—执行」链

### 1.1 嵌入式系统：远程 API 也是一个实时系统

官方 README 明确：评测端逐调用记录**延迟、波动和动作统计规律**，作为结果可信度的一部分；提交要暴露 N 个连续端口，每端口独立完成整个交互流程；多个端口可以共享一个模型，但必须处理并发、避免互相阻塞、保持状态隔离。

这意味着“嵌入式系统”在本轮不是指改机器人固件，而是指：

> **把每端口 PolicyService 当成一个软实时嵌入式服务来设计：有固定的响应预算、有最坏执行时间（WCET）上界、有预分配内存、有看门狗、有降级阶梯；在 CPU 争用和网络抖动下仍然返回形状正确、时间可解释的动作。**

一个具体的账：

```text
H = 5, f_c = 30Hz          -> 执行块 167ms
τ_o (采集→策略) = 30–80ms
W_p (策略计算+序列化) = 10–150ms
τ_a (返回→执行) = 20–80ms
T_fb = 167 + τ_o + W_p + τ_a
```

- 理想：`167 + 30 + 15 + 20 = 232ms`
- 常见：`167 + 50 + 40 + 40 = 297ms`
- 坏情况：`167 + 80 + 150 + 80 = 477ms`

最后 3 厘米的插入/挂杯/拉链/开锁，误差预算只有几毫米；夹爪以 2cm/s 接近时，200ms 就是 4mm。**“伺服算得准”不够，必须“在相位容差允许的时间之前算完”**。

### 1.2 仿真训练：训练一张控制器参数表，不是第二个模型

第 12 轮把仿真限定为标定，理由是 sim-to-real gap 会让仿真里学到的策略在真机上失效。这个理由对“策略”成立，对“控制器参数”不完全成立：

- 仿真的**接触动力学**不可信，所以不能用仿真成功率预测真机成功率；
- 仿真的**时间/计算/遮挡/负载**是可控的，所以可以用仿真找**阶段排序、增益档位、降级阈值**的稳定域；
- 真机数据仍然负责最终校准和 A/B。

STSM 的产物是一张很小的表：

```text
context = (phase, confidence, plan_age, rtt, cpu_load)
         4    ×     2     ×    2    ×  2  ×    2      = 64 桶
entry   = (stage_subset, κ, deadband, certified)
```

在线只做一次量化 + 一次查表，O(1)；没有权重、没有梯度、没有在线学习。它更像 `pid.conf` 里的一张增益表，而不是一个模型。合规上属于第 12 轮的 **C2 确定性控制器**：VLA 是唯一学习模型，表是控制器的参数。

### 1.3 VLA：异步 plan 的“时间锚点”比模型大小更重要

VLA 的动作专家输出的是**相对当前 EE** 的 30 步动作。设 plan 在时刻 `t_a`、EE 位姿 `T_a` 下生成，第 `i` 步的相对动作是 `δ_i`。那么第 `i` 步的绝对目标应该是：

```text
P_i = T_a · exp(δ_i)
```

如果执行时当前 EE 已经变成 `T_t`，有两种常见写法：

```text
正确：直接发送 P_i
错误：发送 Q_i = T_t · exp(δ_i)
```

而

```text
Q_i = T_t · exp(δ_i)
    = (T_t · T_a^{-1}) · T_a · exp(δ_i)
    = ΔT · P_i
```

也就是说，**在执行时重新锚定会把“plan 生成后已经走过的位移 ΔT”再加一遍**。这就是为什么第 12 轮强调“必须先把整个 30 步 compose 成 base 系绝对目标，再按 5 步切片”。本轮把它形式化，并补上第二个错误：

- **空间重锚定错误**：用当前 EE 重新 compose，误差是 `ΔT`；
- **时间重索引错误**：plan 已经老了 `a` 秒，却仍从第 0 步开始执行，误差约 `v·a`。

TPR 做两件事：plan 生成时预 compose；执行时按 `k = clamp(round(a·f_c), 0, H-1)` 跳到当前时刻对应的动作索引。若 `k` 已接近 `H`，说明 plan 过期，丢弃并请求刷新，用伺服/保持兜底。

### 1.4 三者怎么咬合

```text
VLA（异步，30 步 plan）
   │  plan + 锚点 (t_a, T_a)
   ▼
TPR（S0，必做，O(H)）
   │  base 系绝对目标 + 时间重索引
   ▼
ASL（S1–S4，可选，按预算）
   │  PBVS / 双目 / IBVS / 检索
   ▼
DASD（前馈降速，按相位容差）
   │  γ = min(1, e_φ / (v T_fb))
   ▼
RT-Contract（看门狗 + 序列化 + 返回）
   │
   ▼
Evaluator 执行 H 步
```

- **STSM** 决定“在这个上下文里，S1–S4 哪些值得做、增益多少”；
- **RT-Contract** 决定“这次调用还剩多少时间、做到哪一步必须停”；
- **TPR** 决定“用哪一段 plan、锚在哪个位姿”；
- **DASD** 决定“走多快，才能让一个反馈周期内的漂移不超过容差”。

### 2.4 对 DART-SERVO 的硬约束

1. `H` 固定 → 在线不能靠“缩短 chunk”降延迟；只能靠 **减少策略计算时间、按时间重索引、降速、降级**。
2. 无 timestamp → `τ_o` 只能用本地单调时钟 + RTT/2 + 队列长度估计；不能假装有精确采集时刻。
3. 无 depth → 伺服仍以头双目 + 腕部目标图/模板为主；DART 不改变感知源，只改变“在预算内用哪一层”。
4. N 端口共享 GPU → VLA 请求必须 **EDF/least-slack**，否则一个慢请求会拖垮所有端口的 p99。
5. 单模型 → STSM 必须是“控制器参数表”，不能是在线学习的策略；否则走 C1（只用固定保守表）。

## 3. 形式化：时间、预算、稳定性、重锚定

### 3.1 符号

| 符号 | 含义 |
|---|---|
| `H` | 提交时固定的 `action_chunk_size` |
| `f_c` | 评测端控制频率（假设 30Hz，待实测） |
| `τ_o` | 观测年龄：采集 → 策略收到 |
| `τ_a` | 动作年龄：策略返回 → evaluator 开始执行 |
| `W_p` | 策略响应时间：`get_action` 入口到返回 |
| `T_fb` | 反馈周期：`H/f_c + τ_o + W_p + τ_a` |
| `φ` | 任务相位：自由接近 / 预接触 / 接触 / 恢复 |
| `e_φ` | 相位容差（米） |
| `v_φ` | 相位接近速度（米/秒） |
| `D_φ` | 相位截止时间：`e_φ / max(v_φ, v_min)` |
| `D_r` | 响应截止时间：`min(D_r^max, D_φ - H/f_c - τ_o - τ_a)` |
| `w_i` | 阶段 `i` 的最坏执行时间（WCET） |
| `w_s` | 序列化/校验 WCET |
| `v_i(x)` | 阶段 `i` 在上下文 `x` 下的价值 |
| `A` | 选中的可选阶段子集 |
| `κ` | 无量纲增益：`K H / f_c` |
| `d` | 延迟块数：`ceil((τ_o + W_p + τ_a)/(H/f_c))` |

### 3.2 时间模型与可行性

一次调用的时间线：

```text
t_cap --τ_o--> t_req --W_p--> t_ret --τ_a--> t_exec
                                                  │
                                         执行 H/f_c 秒
                                                  ▼
                                          下一次 t_cap'
```

因此：

```math
T_{\mathrm{fb}} = \frac{H}{f_c} + \tau_o + W_p + \tau_a.
```

相位容差给了一个“最多能开环漂多久”的约束。若夹爪以 `v_φ` 接近，一个反馈周期内的漂移约 `v_φ T_fb`；要求不超过 `e_φ`：

```math
v_\phi T_{\mathrm{fb}} \le e_\phi
\quad\Longleftrightarrow\quad
T_{\mathrm{fb}} \le D_\phi = \frac{e_\phi}{v_\phi}.
```

如果 `T_fb > D_φ`，DART 不硬追，而是按比例降速：

```math
\gamma = \min\left(1,\frac{e_\phi}{v_\phi T_{\mathrm{fb}}}\right)
        = \min\left(1,\frac{D_\phi}{T_{\mathrm{fb}}}\right),
\qquad
a_{\mathrm{ff}} \leftarrow \gamma\, a_{\mathrm{ff}}.
```

降速后有效速度是 `γ v_φ`，新的漂移是 `γ v_φ T_fb = e_φ`（当 `γ<1`）。若 `γ < γ_min`（默认 0.2），说明当前环路对任务动态太慢，进入“停—重定位—重规划”，而不是继续追。

### 3.3 预算约束下的阶段选择

把每次 `get_action` 的计算拆成：

- **S0（必做）**：TPR 计划重锚定 + 安全限幅；
- **S1（可选）**：PBVS 粗修正（用缓存的 `T_base_target`）；
- **S2（可选）**：头部双目 ROI 更新目标位姿；
- **S3（可选）**：腕部 IBVS 特征对齐；
- **S4（可选）**：演示检索重排/目标切换；
- **S_serial（必做）**：打包 chunk、token、msgpack。

给定上下文 `x` 和剩余预算 `B`：

```math
A^*(x,B) = \arg\max_{A\subseteq\{1,2,3,4\}}
\left\{
\sum_{i\in A} v_i(x)
\;\middle|\;
w_0 + w_s + \sum_{i\in A} w_i \le B
\right\}.
```

`|{1,2,3,4}| = 4`，只有 16 个子集；在线可以枚举，也可以查预计算表。离线把每个上下文的 16 个子集按价值排序，在线只需要“从高到低找第一个装得下的”，最坏 16 次比较，仍是 O(1)。

**鲁棒版本**：用 `w_i^max = p99.9 + 20%` 而不是均值；预留 `ρ=0.1` 的预算；只有在该鲁棒预算下可行的子集才进入候选。这样即使评测机比开发机慢 20–30%，也不会系统性超时。

### 3.4 稳定性条件

第 12 轮给了一阶离散模型。设误差 `e_k`、增益 `K`、延迟块数 `d`：

```math
e_{k+1} = e_k - \kappa\, e_{k-d},
\qquad \kappa = \frac{K H}{f_c}.
```

特征方程：

```math
z^{d+1} - z^{d} + \kappa = 0.
```

其稳定条件为：

```math
0 < \kappa < 2\sin\!\left(\frac{\pi}{2(2d+1)}\right).
```

数值：

| `d` | 0 | 1 | 2 | 3 | 4 |
|---|---:|---:|---:|---:|---:|
| `κ_max` | 2.000 | 1.000 | 0.618 | 0.445 | 0.347 |

DART 用安全系数 `η=0.5`，即 `κ ≤ 0.5 κ_max(d)`；若 `d` 因 RTT 抖动变大，查表增益自动降档；若 `d ≥ 3`，关闭 IBVS，只做 PBVS + 降速。这个条件是**必要条件**（线性化、单轴、无饱和）；真机还要用 G6 验证。

### 3.5 TPR 的正确性与误差界

**定理（空间重锚定）**：设 `T_a, T_t ∈ SE(3)`，`δ_i ∈ se(3)`。若 plan 时绝对目标 `P_i = T_a exp(δ_i)`，执行时重新 compose `Q_i = T_t exp(δ_i)`，则

```math
Q_i = (T_t T_a^{-1})\,P_i.
```

**证明**：

```math
Q_i = T_t\exp(\delta_i)
    = T_t T_a^{-1} T_a \exp(\delta_i)
    = (T_t T_a^{-1})P_i.
```

证毕。误差 `ΔT = T_t T_a^{-1}` 与 `i` 无关；所以“执行时重新 compose”不是小误差，而是把整段 plan 刚体平移了 `ΔT`。

**定理（时间重索引）**：若 plan 是连续轨迹 `P(s)` 在 `s_i=i/f_c` 的采样，执行时 plan age 为 `a`，选择索引 `k` 的定时误差为 `|a - k/f_c|`，空间误差上界为

```math
\|P(a)-P(k/f_c)\| \le v_{\max}\left|a-\frac{k}{f_c}\right|
\le \frac{v_{\max}}{2f_c}
```

当 `k = round(a f_c)`。若 `a f_c > H-1`，plan 已过期，不能用重索引补救，必须刷新或回退。

**目标移动预测**：若目标在观测年龄 `τ_o` 内以速度 `v_t`、角速度 `ω_t` 运动，一阶预测 `ΔS = exp(ξ τ_o)`，`ξ=(v_t,ω_t)`；预测误差为 `O(||v_t||τ_o + ||ω_t||τ_o + 0.5||a_t||τ_o²)`。协方差超过阈值时不用预测，直接用当前测量 + 降增益。

## 4. 方法：DART-SERVO

### 4.1 总架构

```text
                    ┌──────────────────────────────────────────┐
                    │ Evaluator (N ports 8765..8765+N-1)       │
                    └───────────────┬──────────────────────────┘
                                    │ websocket: obs / action chunk
                                    ▼
        ┌───────────────────────────────────────────────────────┐
        │ Per-port process (CPU, pinned)                        │
        │                                                       │
        │  T_net   websocket recv/send, msgpack, token          │
        │  T_ctrl  S0 TPR + DASD + safety clamp + serialize      │
        │  T_servo S1 PBVS / S2 stereo / S3 IBVS / S4 retrieval │
        │  T_vla   async plan request/response                  │
        │  T_bg    target library / calibration                 │
        │  T_wd    watchdog + WCET accounting                   │
        └───────────────┬───────────────────────────────────────┘
                        │ async, session-id, deadline
                        ▼
        ┌───────────────────────────────────────────────────────┐
        │ Shared VLA server (GPU)                               │
        │ EDF/least-slack queue; batch by earliest deadline      │
        │ UnifoLM-WLA-1.0 / VLA-0, 30-step plan                 │
        └───────────────────────────────────────────────────────┘
```

- 每端口独立进程/独立状态；共享 VLA 权重只读；目标库 mmap 只读。
- 热路径尽量用 C++/pybind11 或独立进程；Python 只做编排。若只能 Python，则用软实时预算 + 2× 余量 + 看门狗，不声称硬实时。
- GPU 队列按“plan 请求的 deadline”排序；过期请求取消，返回旧 plan + 伺服。

### 4.2 RT-Contract

每次 `get_action` 的预算分解：

```text
D_r = min(D_r_max, D_φ - H/f_c - τ_o - τ_a)
B   = D_r - (t_now - t_req) - w_s^max
```

- **Admission**：启动时跑 100 次微基准；若 `w_0^max + w_s^max > D_r`，直接进入 L3（VLA passthrough），并记录告警。
- **Scheduling**：按 STSM 给出的优先级，从高价值阶段开始；每执行一个阶段前检查 `remaining ≥ w_i^max`；不满足就停，返回 best-so-far。
- **Watchdog**：每个阶段有独立计时器；超过 `w_i^max` 置 abort 标志；阶段在安全点检查并退出；返回上一个完整阶段的动作。
- **Serialization**：始终执行；若序列化本身超预算，返回上一组合法 chunk（缓存），并记录一次 deadline miss。

### 4.3 ASL：anytime 伺服阶梯

| 阶段 | 内容 | 输出 | 目标 WCET | 价值 |
|---|---|---|---:|---|
| **S0** | TPR 重锚定 + 时间重索引 + 安全限幅 | base 系绝对目标 `a_ff` | <0.5ms | 必做；防止 `ΔT` 双重计入 |
| **S1** | PBVS：缓存 `T_base_target` + 当前 EE | `Δ_1` | <0.3ms | 粗对齐；无新图也可用 |
| **S2** | 头部双目 ROI 更新 `T_base_target` + 协方差 | `Δ_2` | <8ms @240×320 ROI | 处理位置/人为干扰 |
| **S3** | 腕部 IBVS：目标图/模板特征对齐 | `Δ_3` | <6ms @128×128 | 最后 1–2cm 横向精度 |
| **S4** | 演示检索重排/目标切换 | 新 goal | <10ms | 阶段/目标不确定时纠错 |

动作合成：

```text
a_cmd = a_ff ∘ exp(Δ_A)
Δ_A   = 最后一个成功阶段的修正（前面的阶段提供初始化/门控）
```

- 阶段之间不简单相加，而是**后者覆盖前者**：S1 给粗对齐，S2 更新目标，S3 在更新后的目标上做局部对齐；避免两个独立修正叠加导致超调。
- 每个阶段输出都带协方差/置信度；置信度低于阈值时，该阶段不覆盖上一阶段。
- S0 的安全限幅永远最后执行：位置每块 ≤1cm、旋转每块 ≤0.05rad、速度/加速度限幅。

### 4.4 STSM：仿真训练调度表

**上下文离散化（64 桶）**：

| 维度 | 取值 | 说明 |
|---|---|---|
| `φ` | 自由 / 预接触 / 接触 / 恢复 | 4 |
| `c` | 低 / 高 | 目标位姿/特征置信度 |
| `a` | 新 / 旧 | plan age <100ms / ≥100ms |
| `τ` | 低 / 高 | 估计 RTT <50ms / ≥50ms |
| `q` | 轻 / 重 | CPU 负载/端口数 |

**候选配置（每桶 128 个）**：

- 16 个阶段子集 `A ⊆ {S1,S2,S3,S4}`；
- `κ ∈ {0.2, 0.4, 0.6, 0.8}`；
- 死区 `δ_p ∈ {2mm, 5mm}`；
- 共 `16×4×2=128`。

**仿真 rollout**：

```text
for family in {peg-in-hole, hang/stack, zip/unlock}:
  for context in 64 buckets:
    for candidate in 128:
      for rollout in 1..20:
        randomize target pose, occlusion, background, RTT/jitter,
                   CPU cost scale (0.7–1.3), perception noise
        run closed-loop with DART
        record success, final error, overshoot, compute time, deadline miss
```

规模：`3 × 64 × 128 × 20 = 491,520` episodes；若 10s episode 在仿真里 0.1s 完成（100× 实时），约 **13.7 GPU-hours**；加鲁棒复评约 **1 GPU-day**。

**目标函数**：

```math
J(c) = \mathrm{success}
     - \lambda_1\,\mathrm{mean\_final\_error}
     - \lambda_2\,\mathrm{p99\_compute}
     - \lambda_3\,\mathrm{deadline\_miss}.
```

**鲁棒认证**：

1. 时间扰动：把每个 `w_i` 乘 `1+ε`，`ε∈[-0.3,0.3]`；要求最优子集在 ≥90% 扰动下不变，成功率下降 ≤5pp。
2. 感知扰动：置信度噪声、遮挡、目标移动；要求成功率下降 ≤5pp。
3. 只把通过认证的条目写进表；未通过的桶用保守前缀（S0+S1，κ=0.3，死区 5mm）。

**在线查表**：

```text
x = quantize(phase, confidence, plan_age, rtt, cpu_load)
entry = table[x]
if not entry.certified: entry = conservative
A, κ, δ_p = entry
```

查表 O(1)，表大小 <1KB；不随 N 端口增长。

### 4.5 TPR：时间重锚定与重索引

**离线/plan 时**：

```text
request plan at t_a with obs o_a, EE pose T_a
when plan δ[0..H-1] arrives:
    P[i] = T_a @ exp(δ[i])        # base-frame absolute targets
    store (t_a, T_a, P, o_a)
```

**执行时**：

```text
a = t_now - t_a
k = clamp(round(a * f_c), 0, H-1)
if a * f_c > H - H_c:             # plan too old for this chunk
    request refresh; use servo/hold tail
tail = P[k : k+H_c]               # pad with P[H-1] if short
if target moved and prediction confident:
    tail = ΔS_pred @ tail         # left multiply
```

**关键纪律**：

- 永远不在执行时用当前 EE 重新 compose 相对动作；
- 永远不从过期的第 0 步开始执行；
- 永远给返回的 chunk 做形状/范围/token 校验；
- plan 过期或帧约定不确定时，回退到 VLA passthrough 或保持，不猜。

### 4.6 降级阶梯

| 级别 | 条件 | 行为 | 恢复 |
|---|---|---|---|
| **L0 Full** | 预算充足、置信度高 | S0–S4 全开 | — |
| **L1 No-Retrieval** | 预算中等 | S0–S3 | 连续 10 次预算充足 |
| **L2 PBVS-only** | 预算紧/腕部无效 | S0+S1（+S2 若够） | 连续 20 次预算充足且置信度高 |
| **L3 VLA passthrough** | `D_r` 不可行/连续超时 | 直接返回缓存 plan + 安全限幅 | 手动/重置后重试 |
| **L4 Hold** | 动作异常/目标丢失/编辑检测 | 保持当前位置，请求重规划 | 目标重新可见 |

- 降级是**立即**的（安全优先）；升级是**滞后**的（避免抖动）。
- 每次降级/升级都记录原因、时间、上下文；用于离线分析和 STSM 更新。
- L3/L4 也必须返回合法形状和 token；绝不返回 NaN/Inf/错误维度。

| 风险 | 影响 | 缓解 |
|---|---|---|

## 8. 一句话押注

**用仿真训练一张可审计的控制器参数表，用 WCET 预算和看门狗保证每次 `get_action` 在截止时间内返回 best-so-far，用 TPR 把异步 VLA plan 按时间重锚定，用 DASD 把开环漂移压回任务容差——在不新增学习模型、不改变固定 chunk 的前提下，让 CHUNK-SERVO 的 167ms 闭环在真实远程 API 上可预测地发生。**

| 观测图像 | 4 路 RGB 480×640：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` | ROI/分辨率是计算预算的主要杠杆 |
| 本体 | 左右臂 7、EE 位姿 6（base 系 xyz+rpy）、夹爪 1、下身体 15、语言 `str` | 无 timestamp；时间只能用本地时钟 + RTT/2 估计 |
| 动作 | `joint` 或 `ee` 互斥；共享 `left_gripper`、`right_gripper`、`pivot[7]` | `pivot` 语义需 G0 验证；先零 pivot |
| 缺失 | 无 depth、camera_info、force/torque、tactile | 伺服仍是几何/图像；无接触力闭环 |
| 端口 | N 个连续端口从 8765 起；每端口独立；共享模型需处理并发和状态隔离 | 每端口进程 + GPU EDF |
| 可信度 | 评测端逐调用记录延迟、波动、动作统计规律 | p99 和 deadline miss 是主指标，不只是成功率 |
| token | metadata 一次握手 + 每次 `get_action` 的 `meta.token` | 序列化阶段必做；不能让 token 校验成为超时源 |

**关键推论**：`T_fb = H/f_c + τ_o + W_p + τ_a`。在 H 固定的前提下，降低反馈延迟只能从 `W_p`（策略计算）、`τ_o`（观测年龄）、`τ_a`（动作年龄）和运动速度（DASD）入手。DART 的四条杠杆正好对应这四项。

## 2. 问题形式化

### 2.1 符号定义

### 2.2 时间模型

一次调用的时间线：

```text
t_cap ──τ_o──▶ t_req ──W_p──▶ t_ret ──τ_a──▶ t_exec
                                                   │
                                         执行 H/f_c 秒
                                                   ▼
                                           下一次 t_cap'
```

```math
T_{\mathrm{fb}} = \frac{H}{f_c} + \tau_o + W_p + \tau_a.
```

由于 API 没有 timestamp，`τ_o` 的在线估计为：

```math
\hat\tau_o = \frac{\widehat{\mathrm{RTT}}}{2} + \hat q_{\mathrm{recv}},
```

其中 `q_recv` 是本地接收队列/解码延迟，用单调时钟测量。这个估计有偏，但 DART 只用它做**保守预算**和**降速**，不用它做精确时间同步；偏差通过安全系数吸收。

### 2.3 相位截止与可行性

相位容差与接近速度给出“最多能开环漂多久”：

```math
D_\phi = \frac{e_\phi}{\max(v_\phi, v_{\min})}.
```

可行条件：

```math
T_{\mathrm{fb}} \le D_\phi
\quad\Longleftrightarrow\quad
W_p \le D_\phi - \frac{H}{f_c} - \tau_o - \tau_a.
```

定义响应截止：

```math
D_r = \min\left(D_r^{\max},\; D_\phi - \frac{H}{f_c} - \tau_o - \tau_a\right).
```

若 `D_r < w_0 + w_s`，则**没有**任何伺服阶段能按时完成；直接进入 L3（VLA passthrough），并记录一次不可行。若 `D_r ≥ w_0 + w_s`，进入 anytime 调度。

**相位参数（C 级设计假设，需 G6 校准）**：

| 相位 | `e_φ` | `v_φ` | `D_φ` | 读法 |
|---|---:|---:|---:|---|
| 自由接近 F | 20mm | 100mm/s | 200ms | 粗定位，容差大 |
| 预接触 P | 5mm | 20mm/s | 250ms | 开始减速 |
| 接触 C | 2mm | 10mm/s | 200ms | 插入/挂/拉链 |
| 恢复 R | 10mm | 30mm/s | 333ms | 人移动目标后 |

这些数值不是实测；它们只是把“最后 3 厘米”翻译成时间预算。G6 会用真实单任务数据反推 `e_φ/v_φ`，并检查 `D_φ` 与成功率的单调关系。

### 2.4 预算约束下的阶段选择

给定上下文 `x` 和预算 `B`：

```math
A^*(x,B) =
\arg\max_{A\subseteq\{1,2,3,4\}}
\left\{
\sum_{i\in A} v_i(x)
\;\middle|\;
w_0 + w_s + \sum_{i\in A} w_i^{\max} \le B
\right\}.
```

- `w_i^max` 用 `p99.9 + 20%`，不是均值；
- 预留 `ρ=0.1` 的安全预算：`B_eff = (1-ρ)B`；
- 若并列，选阶段数少的（更少抖动）；
- 若所有非空子集都不可行，选 `A=∅`，只做 S0 + 序列化。

在线实现有两种：

1. **枚举**：16 个子集，按价值降序检查可行性，最坏 16 次比较；
2. **查表**：STSM 直接给出 `(A, κ, δ_p)`，O(1)。

两者都用同一份离线表；枚举用于表外上下文/回退。

### 2.5 稳定性条件

一阶离散误差模型：

```math
e_{k+1} = e_k - \kappa e_{k-d},
\qquad \kappa = \frac{K H}{f_c}.
```

特征方程：

```math
z^{d+1} - z^{d} + \kappa = 0.
```

稳定条件：

```math
0 < \kappa < 2\sin\!\left(\frac{\pi}{2(2d+1)}\right).
```

| `d` | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|---:|
| `κ_max` | 2.000 | 1.000 | 0.618 | 0.445 | 0.347 | 0.285 |
| `κ` with `η=0.5` | 1.000 | 0.500 | 0.309 | 0.222 | 0.173 | 0.142 |

DART 的增益表按 `d` 和 `φ` 查；若 `d` 因 RTT 抖动跨档，取更保守的一档。若 `d ≥ 3`，关闭 IBVS（S3），只做 PBVS + DASD，因为高延迟下高频视觉修正会振荡。

### 2.6 TPR 的正确性与误差界

**定理 1（空间重锚定）**：设 `T_a, T_t ∈ SE(3)`，`δ_i ∈ se(3)`，plan 时绝对目标 `P_i = T_a exp(δ_i)`，执行时重新 compose `Q_i = T_t exp(δ_i)`。则

```math
Q_i = (T_t T_a^{-1}) P_i.
```

**证明**：

```math
Q_i = T_t \exp(\delta_i)
    = T_t T_a^{-1} T_a \exp(\delta_i)
    = (T_t T_a^{-1}) P_i.
```

证毕。误差 `ΔT = T_t T_a^{-1}` 与 `i` 无关；执行时重新 compose 会把整段 plan 刚体平移 `ΔT`，不是小误差。

**定理 2（时间重索引）**：若 plan 是连续轨迹 `P(s)` 在 `s_i=i/f_c` 的采样，plan age 为 `a`，选择 `k=round(a f_c)`，则定时误差 ≤ `1/(2f_c)`，空间误差上界

```math
\|P(a)-P(k/f_c)\| \le \frac{v_{\max}}{2f_c}.
```

若 `a f_c > H-1`，plan 已过期，重索引无法补救；必须刷新或用伺服/保持兜底。

**目标移动预测**：若目标在 `τ_o` 内以 `(v_t,ω_t)` 运动，一阶预测

```math
\Delta S_{\mathrm{pred}} = \exp(\xi \tau_o),
\qquad \xi=(v_t,\omega_t),
```

预测误差 `O(||v_t||τ_o + ||ω_t||τ_o + 0.5||a_t||τ_o²)`。协方差超过阈值时不用预测，直接当前测量 + 降增益。

## 3. DART-SERVO 算法

### 3.1 总架构

```text
                    ┌──────────────────────────────────────────┐
                    │ Evaluator (N ports 8765..8765+N-1)       │
                    └───────────────┬──────────────────────────┘
                                    │ websocket: obs / action chunk
                                    ▼
        ┌───────────────────────────────────────────────────────┐
        │ Per-port process (CPU, pinned)                        │
        │                                                       │
        │  T_net   websocket recv/send, msgpack, token          │
        │  T_ctrl  S0 TPR + DASD + safety clamp + serialize      │
        │  T_servo S1 PBVS / S2 stereo / S3 IBVS / S4 retrieval │
        │  T_vla   async plan request/response                  │
        │  T_bg    target library / calibration                 │
        │  T_wd    watchdog + WCET accounting                   │
        └───────────────┬───────────────────────────────────────┘
                        │ async, session-id, deadline
                        ▼
        ┌───────────────────────────────────────────────────────┐
        │ Shared VLA server (GPU)                               │
        │ EDF/least-slack queue; batch by earliest deadline      │
        │ UnifoLM-WLA-1.0 / VLA-0, 30-step plan                 │
        └───────────────────────────────────────────────────────┘
```

- 每端口独立进程：独立 `reset()`、独立 plan cache、独立 goal 状态、独立 WCET 统计。
- 共享 VLA 权重只读；session ID 区分端口；请求带 deadline；过期取消。
- 目标库 mmap 只读；STSM 表只读；日志用无锁 ring buffer。
- 热路径尽量 C++/pybind11；Python 只做编排。若只能 Python，用软实时预算 + 2× 余量。

### 3.2 阶段定义与动作合成

| 阶段 | 输入 | 输出 | 目标 WCET | 失败回退 |
|---|---|---|---:|---|
| **S0** TPR | cached plan、`(t_a,T_a)`、当前 EE、plan age | `a_ff`：base 系绝对目标 | <0.5ms | 用上一组合法 chunk / hold |
| **S1** PBVS | 缓存 `T_base_target`、当前 EE | `Δ_1` | <0.3ms | `Δ=0` |
| **S2** 双目 ROI | 头部左右图、ROI、上一目标位姿 | 更新 `T_base_target` + 协方差 | <8ms @240×320 ROI | 保留旧目标 |
| **S3** 腕部 IBVS | 腕部图、目标图/模板、深度先验 | `Δ_3` | <6ms @128×128 | `Δ=0` |
| **S4** 检索重排 | 描述子、任务/相位、位姿先验 | 新 goal | <10ms | 保留旧 goal |
| **S_serial** | 动作、token | msgpack chunk | <1ms | 返回缓存 chunk |

动作合成：

```text
a_cmd = a_ff ∘ exp(Δ_A)
Δ_A   = 最后一个成功且有置信度的阶段修正
```

- 阶段之间是**覆盖**关系，不是相加：S1 给粗对齐，S2 更新目标，S3 在更新后的目标上做局部对齐。
- 每个阶段输出 `(Δ, Σ, confidence)`；置信度低于阈值不覆盖。
- S0 之后、序列化之前，始终执行安全限幅：位置每块 ≤1cm、旋转每块 ≤0.05rad、速度/加速度限幅、NaN/Inf 检查。

### 3.3 `get_action` 伪代码

```python
class DARTProxy:
    def get_action(self, obs):
        t_req = mono_ns()
        self._validate_obs(obs)
        self._update_context(obs, t_req)          # phase, confidence, rtt, load
        self._maybe_request_plan(obs, t_req)      # async, non-blocking

        D_r = self._response_deadline()           # eq. §2.3
        budget = D_r - (mono_ns() - t_req) / 1e9 - self.w_serial_max
        if budget < self.w0_max:
            return self._fallback_chunk(obs, "L3_no_budget")

        entry = self.stsm.lookup(self.context)
        stages = entry.stage_order              # e.g. [S1,S2,S3,S4]
        a_ff = self._s0_tpr(obs)                # mandatory
        if a_ff is None:
            return self._fallback_chunk(obs, "L3_plan_invalid")

        delta = None
        for st in stages:
            if budget < self.w_max[st]:
                break
            t0 = mono_ns()
            out = self._run_stage(st, obs, self.goal)
            dt = (mono_ns() - t0) / 1e9
            self._account(st, dt)
            if out is not None and out.confidence >= self.c_min[st]:
                delta = out.delta
                self.goal = out.goal or self.goal
            budget -= self.w_max[st]            # conservative accounting
            if self._watchdog_fired(st):
                self._degrade("watchdog")
                break

        a_ff = self._dasd_feedforward(a_ff, obs)  # γ scaling, §3.5
        if a_ff is None:
            return self._fallback_chunk(obs, "L4_too_dynamic")
        a_cmd = compose(a_ff, delta) if delta is not None else a_ff
        a_cmd = self._safety_clamp(a_cmd, obs)
        a_cmd = self._validate_action(a_cmd)
        return self._serialize(a_cmd, self.token)
```

### 3.4 异步 plan 管理

```python
def _maybe_request_plan(self, obs, t_req):
    if self.future is not None and not self.future.done():
        return
    if self.future is not None:
        plan = self.future.result()
        self.plan = Plan(
            t_a=self.plan_t_a,
            T_a=self.plan_T_a,
            P=precompose(self.plan_T_a, plan.actions),  # base-frame absolute
            obs=self.plan_obs,
        )
        self.future = None

    if self.plan is None or self._plan_age(t_req) > self.plan_ttl:
        self.plan_t_a = t_req
        self.plan_T_a = current_ee_pose(obs)
        self.plan_obs = copy.deepcopy(obs)
        self.future = self.executor.submit(self.vla.predict, self.plan_obs)
```

规则：

- plan 请求永不阻塞 `get_action`；冷启动可以同步一次，但设超时。
- plan 过期（`age > H/f_c` 或 `k+H_c > H`）就丢弃；用上一 plan 的尾部 + 伺服，或 L3。
- 新 plan 到达时，不要从第 0 步执行；用 TPR 重索引。
- 每个 plan 记录 `t_a, T_a, o_a`，用于误差分析。

### 3.5 TPR + DASD

```python
def _s0_tpr(self, obs):
    if self.plan is None:
        return None
    age = (mono_ns() - self.plan.t_a) / 1e9
    k = clamp(round(age * self.f_c), 0, self.H - 1)
    if age * self.f_c > self.H - self.H_c:
        self._request_refresh()
        return None
    tail = self.plan.P[k : k + self.H_c]
    if len(tail) < self.H_c:
        tail = np.concatenate([tail, np.repeat(tail[-1:], self.H_c - len(tail), axis=0)])
    if self._target_prediction_confident():
        tail = apply_left(self.pred_delta, tail)
    return tail

def _dasd_feedforward(self, a_ff, obs):
    v = estimate_closing_speed(obs, a_ff)
    T_fb = self._estimate_feedback_period()
    D_phi = self.e_phi / max(v, self.v_min)
    gamma = min(1.0, D_phi / max(T_fb, 1e-6))
    if gamma < self.gamma_min:
        self._degrade("too_dynamic")
        return None
    return scale_feedforward(a_ff, gamma)
```

**DASD 的语义**：`γ` 只缩放前馈位移/速度，不缩放夹爪开合、不缩放安全限幅后的绝对位置；它把“一个反馈周期内的开环漂移”压到 `e_φ`。如果 `γ<γ_min`，说明环路对任务动态太慢，继续追会超调；停/重定位/重规划更安全。

### 3.6 RT-Contract 与降级

**预算分解**：

```text
D_r = min(D_r_max, D_φ - H/f_c - τ_o - τ_a)
B   = D_r - (t_now - t_req) - w_s_max
```

**Admission**：

```text
if w_0_max + w_s_max > D_r:
    mode = L3
    log("infeasible", D_r, w_0_max, w_s_max)
```

**Watchdog**：

- 每阶段独立计时；超过 `w_i_max` 置 abort；
- 阶段在安全点（循环边界、图像 ROI 边界）检查 abort；
- abort 后返回上一个完整阶段的动作；记录一次 overrun；
- 连续 3 次 overrun → 降一级；连续 20 次无 overrun → 升一级。

**降级阶梯**：

| 级别 | 条件 | 行为 | 恢复 |
|---|---|---|---|
| L0 Full | 预算充足、置信度高 | S0–S4 | — |
| L1 No-Retrieval | 预算中等 | S0–S3 | 连续 10 次预算充足 |
| L2 PBVS-only | 预算紧/腕部无效 | S0+S1（+S2 若够） | 连续 20 次预算充足且置信度高 |
| L3 VLA passthrough | `D_r` 不可行/连续超时 | 缓存 plan + 安全限幅 | 手动/重置后重试 |
| L4 Hold | 动作异常/目标丢失/编辑检测 | 保持当前位置，请求重规划 | 目标重新可见 |

降级立即，升级滞后；每次切换记录 `(t, from, to, reason, context, metrics)`。

### 3.7 STSM：仿真训练调度表

#### 3.7.1 上下文桶（64 个）

| 维度 | 取值 | 数量 |
|---|---|---:|
| `φ` | F / P / C / R | 4 |
| `c` | 低 / 高（目标位姿/特征置信度） | 2 |
| `a` | 新 / 旧（plan age <100ms / ≥100ms） | 2 |
| `τ` | 低 / 高（估计 RTT <50ms / ≥50ms） | 2 |
| `q` | 轻 / 重（CPU 负载/端口数） | 2 |

总计 `4×2×2×2×2 = 64` 桶。

#### 3.7.2 候选配置（每桶 128 个）

- 16 个阶段子集 `A ⊆ {S1,S2,S3,S4}`；
- `κ ∈ {0.2,0.4,0.6,0.8}`（4）；
- 死区 `δ_p ∈ {2mm,5mm}`（2）；
- 总计 `16×4×2=128`。

#### 3.7.3 仿真协议

```text
for family in {peg-in-hole, hang/stack, zip/unlock}:
  for context in 64 buckets:
    for candidate in 128:
      for rollout in 1..20:
        randomize:
          target pose ~ task distribution
          occlusion / background / human hand
          RTT ∈ {0,50,100,150,200} ms + jitter
          CPU cost scale ∈ [0.7,1.3]
          perception noise / confidence error
        run DART closed-loop for one episode
        record success, final error, overshoot,
               compute time, deadline miss, degradation count
```

规模：`3×64×128×20 = 491,520` episodes。若 10s episode 在仿真里 0.1s 完成（100× 实时），约 **13.7 GPU-hours**；加鲁棒复评约 **1 GPU-day**。若算力不足，先做 2 个 family × 32 桶 × 64 候选 × 10 rollout = 40,960 episodes，约 1.1 GPU-hours，先验证趋势。

#### 3.7.4 目标函数与选择

```math
J(c) = \mathrm{success}
     - \lambda_1\,\mathrm{mean\_final\_error}
     - \lambda_2\,\mathrm{p99\_compute}
     - \lambda_3\,\mathrm{deadline\_miss}
     - \lambda_4\,\mathrm{degradation\_rate}.
```

默认权重 `λ1=1/mm`、`λ2=1/10ms`、`λ3=1`、`λ4=0.1`；权重需在验证集上固定，不能按测试结果调。每个桶保留 Pareto 前沿上的 1–3 个候选，最终只写一个“认证候选”。

#### 3.7.5 鲁棒认证

1. **时间扰动**：`w_i ← w_i(1+ε)`，`ε∈[-0.3,0.3]`，100 次；要求最优子集在 ≥90% 扰动下不变，成功率下降 ≤5pp。
2. **感知扰动**：置信度噪声、遮挡、目标移动；要求成功率下降 ≤5pp。
3. **跨 family 一致性**：同一相位桶在两个 family 上的最优子集不应完全相反；若相反，降级为保守前缀。
4. **未认证回退**：`A={S1}`、`κ=0.3`、`δ_p=5mm`。

#### 3.7.6 在线查表

```text
x = (phase_id, conf_id, age_id, rtt_id, load_id)
entry = table[x]
if not entry.certified:
    entry = CONSERVATIVE
A, kappa, deadband = entry
```

查表 O(1)；表大小 64 × 4 bytes ≈ 256 bytes；可忽略。

### 3.8 复杂度与内存

**在线（每次 `get_action`）**：

| 操作 | 复杂度 | 说明 |
|---|---|---|
| 上下文量化 + 查表 | O(1) | 64 桶 |
| S0 TPR | O(H) | H≤30；纯矩阵乘法 |
| 阶段执行 | O(Σ ROI_i) | ROI 固定上限；S2/S3 是主成本 |
| 动作合成/限幅 | O(H) | ≤30×21 浮点 |
| 序列化 | O(H) | msgpack |
| **总计** | **O(H + Σ ROI_i) = O(1)** | H、ROI、m 都是固定上界 |

**离线**：

- STSM：`O(|X|·|C|·R)`，`|X|=64`，`|C|=128`，`R=20`，3 families。
- WCET 微基准：`O(K·S)`，K=10,000 次/阶段。
- 回放：`O(E·H)`，E=33,276。

**内存（每端口）**：

| 项 | 估算 |
|---|---:|
| 图像双缓冲（4 路，resize 后） | ~8–16MB |
| plan + 动作缓存 | <1MB |
| 特征/ROI | <4MB |
| STSM 表 | <1KB |
| Python/库开销 | ~100–200MB |
| 目标库（共享只读） | 200–400MB |
| **每端口合计** | **<500MB** |

N=3 时 <1.5GB；目标库共享，不随 N 线性增长。

## 4. 正确性论证

### 4.1 定理 3（截止时间安全）

**假设**：

1. `w_i^max` 是阶段 i 的有效 WCET 上界（实测 p99.9 + 20%）；
2. `w_s^max` 是序列化上界；
3. 调度器只选择满足 `w_0 + w_s + Σ_{i∈A} w_i^max ≤ B` 的 A；
4. 看门狗在阶段超过 `w_i^max` 时置 abort，阶段在安全点退出。

**结论**：每次 `get_action` 在 `D_r` 内返回一个形状合法的动作；若某阶段被 abort，返回上一个完整阶段的动作。

**证明**：S0 和序列化的预算在 admission 时检查；每个可选阶段执行前检查剩余预算；看门狗保证单阶段不超过 `w_i^max`；abort 后不再启动新阶段，直接合成 best-so-far 并序列化。因此总时间 ≤ `w_0 + w_s + Σ w_i^max ≤ B`，加上已消耗时间 ≤ `D_r`。若 S0 本身失败，走 L3/L4 的缓存/保持路径，该路径的动作是预分配且预校验的。证毕。

**注意**：这是软实时保证，依赖 WCET 上界在评测机上仍成立。若评测机更慢，`w_i^max` 失效；DART 用 2× 余量 + 看门狗 + admission 降低风险，但不能证明硬实时。

### 4.2 定理 4（anytime 单调性）

**定义**：`V(A|x)=Σ_{i∈A} v_i(x)`，`v_i(x)≥0`；阶段按价值降序排列。**结论**：在预算允许时，增加一个阶段不会降低调度器的价值；`V(A∪{i}) ≥ V(A)`。

**证明**：由 `v_i≥0`，直接相加。证毕。

**注意**：这是**调度器价值**的单调性，不是物理误差的严格单调性。物理上，S3 可能覆盖 S1，若 S3 的估计更差，误差可能变大。为此 DART 用置信度门控和“后者覆盖前者”而不是相加；并把物理误差的单调性作为 G7 的验证项，而不是定理。

### 4.3 定理 5（稳定性）

**模型**：`e_{k+1}=e_k-κ e_{k-d}`，`κ=K H/f_c`。**结论**：若 `0<κ<2 sin(π/(2(2d+1)))`，零平衡点渐近稳定。

**证明思路**：特征方程 `z^{d+1}-z^d+κ=0`。用 Schur-Cohn 判据或根轨迹：当 `κ→0`，一个根在 1 附近，其余在 0；随 `κ` 增大，主导根沿单位圆走，临界点在 `z=e^{jθ}` 满足 `e^{j(d+1)θ}-e^{jdθ}+κ=0`。分离实虚部可得 `κ=2 sin(θ/2)` 且 `θ=π/(2d+1)`，即 `κ_max=2 sin(π/(2(2d+1)))`。证毕（略去代数细节）。

**用法**：DART 取 `η=0.5` 的安全系数；若 `d` 跨档，取更保守的 `κ`。这是线性化必要条件，真机饱和/摩擦/柔顺会改变稳定域，必须 G6 验证。

### 4.4 定理 6（TPR 空间/时间误差）

**空间**：定理 1 已证 `Q_i=(T_t T_a^{-1})P_i`；预 compose 的 `P_i` 不包含 `ΔT`，所以不会双重计入。若 `T_a` 有标定误差 `ε_a`、`T_t` 有估计误差 `ε_t`，则 `P_i` 的误差上界为 `||ε_a||+||ε_t||`（一阶）。

**时间**：定理 2 已证重索引误差 ≤ `v_max/(2f_c)`；若 `a f_c > H-1`，plan 过期，重索引无法补救，必须刷新。

**目标移动**：一阶预测误差 `O(||v_t||τ_o+||ω_t||τ_o+0.5||a_t||τ_o²)`；协方差门控保证只在可预测时使用。

### 4.5 定理 7（复杂度）

**在线**：查表 O(1)，TPR O(H)，阶段 O(Σ ROI_i)，序列化 O(H)。H≤30、ROI 固定、阶段数 5，所以总时间是常数上界；内存 O(N·(image + plan + table))。

**离线**：STSM `O(|X||C|R)`；回放 `O(EH)`；微基准 `O(KS)`。

**证明**：逐项计数；所有循环上界由固定常数限制。证毕。

### 4.6 局限

- 定理 3 是软实时，不是硬实时；WCET 依赖评测机。
- 定理 4 是调度器价值，不是物理误差。
- 定理 5 是线性化、单轴、无饱和；真机需验证。
- 定理 6 假设 `T_a,T_t` 的帧约定一致；TCP/工具坐标偏移会破坏。
- STSM 的价值函数是仿真估计，不是可证明的最优策略；G2 只验证“相对 oracle 的 regret”，不承诺真机最优。

## 6. 嵌入式实现

### 6.1 每端口进程/线程

| 线程 | 职责 | 优先级 | 亲和性 |
|---|---|---:|---|
| `T_wd` | 看门狗、WCET 统计 | 99 | core 0 |
| `T_net` | websocket、msgpack、token | 90 | core 0 |
| `T_ctrl` | S0 + DASD + 限幅 + 序列化 | 80 | core 0 |
| `T_servo` | S1–S4 | 70 | core 1 |
| `T_vla` | 异步 plan 请求/响应 | 50 | core 2 |
| `T_bg` | 目标库/标定 | 10 | core 3 |

- Python 线程受 GIL 限制；S2/S3 的重计算应放在 C++/pybind11 或独立进程。
- 若只能用 Python：用 `concurrent.futures.ProcessPoolExecutor` 做伺服，主进程只做编排；用 `gc.disable()` + 每 episode `gc.collect()`；`cv2.setNumThreads(1)`；`OMP_NUM_THREADS=1`。
- CPU governor 设 performance；关闭超线程争用；NUMA 绑核（如多 socket）。

### 6.2 内存

- 启动时预分配所有图像/特/征/动作缓冲；热路径零 `malloc/free`。
- 用固定大小 arena + 对象池；图像用双缓冲/三缓冲，最新帧覆盖旧帧。
- 日志用无锁 ring buffer；不在热路径格式化字符串。
- `reset()` 只重置状态指针，不重新分配大块内存；每个 episode 后做一次内存泄漏检查。

### 6.3 无锁队列

- `T_net → T_ctrl`：latest-observation slot（seqlock，读者重试）。
- `T_ctrl → T_servo`：SPSC 请求队列（固定容量 1–2）。
- `T_servo → T_ctrl`：SPSC 结果队列（固定容量 1）。
- `T_vla → T_ctrl`：plan slot（带版本号/seqlock）。
- 所有队列容量固定；满时覆盖最旧（伺服）或丢弃（日志），不阻塞。

### 6.4 WCET 测量协议

1. 在**目标部署容器**上测，不在开发机。
2. 每阶段 10,000 次，输入分布覆盖：全图/ROI、成功/失败、低/高置信度。
3. 记录 p50/p90/p99/p99.9/max；`w_i^max = p99.9 × 1.2`。
4. 在 1/2/4 端口并发下重复；取最坏。
5. 每次部署/升级 OpenCV/numpy/Python 后重测；表版本与 WCET 版本绑定。
6. 上线后每 1000 次调用抽样复测；若 p99.9 超 `w_i^max`，自动降级并告警。

### 6.5 N 端口与 GPU EDF

- 每端口独立进程；端口 8765..8765+N-1；健康检查/自动重启。
- VLA 请求带 `deadline = t_req + TTL`；GPU 队列按 EDF 排序；批处理只合并“最早 deadline 仍能赶上”的请求。
- 若某端口请求过期，取消并返回旧 plan + 伺服；不阻塞其他端口。
- 目标库/STSM 表只读共享；每个端口独立 plan cache/goal/state。
- 记录每端口 p50/p99、deadline miss、降级次数；用于赛后分析。

### 6.6 看门狗与降级

```text
watchdog:
  for each stage:
    if elapsed > w_i_max:
      abort_flag[stage] = True
      overrun_count[stage] += 1
  if overrun_count[stage] >= 3 in 10s:
    degrade_one_level()
  if no overrun in 20 cycles:
    maybe_upgrade_one_level()
```

- abort 只在安全点生效；不会硬杀线程（避免状态不一致）。
- 降级立即；升级滞后；每次切换记录原因。
- L4 Hold 也要返回合法动作（保持当前位置 + 夹爪保持）。

### 6.7 部署清单

- [ ] 目标容器 WCET 微基准通过。
- [ ] `w_0^max + w_s^max ≤ D_r` admission 通过。
- [ ] token/chunk 形状/`pivot` 零回退本地验证。
- [ ] N 端口本地并发 30min 无串扰。
- [ ] 内存 30min 不涨。
- [ ] 看门狗注入超时测试通过。
- [ ] 回滚开关可用（一键回 CHUNK-SERVO 固定表）。
- [ ] 日志不包含 token/敏感信息。

| 去 STSM（固定 S0+S1） | 验证仿真训练表 |
| 去 DASD | 验证降速 |
| 去看门狗 | 验证截止时间安全 |
| 去 N 端口 EDF | 验证队列 |
| 固定 `κ=0.6` vs 查表 | 验证增益调度 |

**门 G7**：全量在每个主指标上不劣于消融；至少 3 个消融显著变差。

### 7.8 门 G0–G10

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | API/契约 | token、形状、`pivot` 零回退、N 端口跑通 | 回退基线 |
| G1 | WCET | S0+S p99.9 ≤20ms；全梯 p99 ≤50ms（N=1） | 缩小 ROI/C++ |
| G2 | STSM | 认证 ≥80%；regret ≤5pp | 保守固定表 |
| G3 | TPR | 误差降 ≥50%；重索引降 ≥30% | 关闭 TPR |
| G4 | 单任务 | 3/5 +10pp 或 p99 降 ≥30% | 不交 DART |
| G5 | N 端口 | 无串扰；p99 ≤150ms | 减 N/回退 |
| G6 | 延迟 | τ≤150ms 稳定；降 ≤10pp | 降增益/DASD/只 PBVS |
| G7 | 消融 | 全量 > 消融 | 保留有效部分 |
| G8 | 全量干跑 | 32×10 无超时/NaN/reset 干净 | 回退基线 |
| G9 | 合规 | 单模型说明、表无权重、无在线学习 | C1 固定表 |
| G10 | 提交 | 回滚/日志/健康检查 | 不交 |

### 7.9 统计

- 320 trials 下 `p≈0.25` 的 SE ≈2.42pp；+1–2pp 不能当结论。
- 配对 A/B 用差值 bootstrap 95% CI；报告 CI，不只报均值。
- 延迟用 p50/p95/p99/p99.9 和 deadline miss；不只看均值。
- STSM 用留出上下文/留出 family 的 regret；不要在同一批 rollout 上选表又评估。

## 8. 竞赛策略

### 8.1 任务组合（沿用第 12 轮先验）

- **A 档：伺服优先（19）**：HangCup、DisconnectEthernet、ToolboxStorage、PlugCharger、Unlock、ArrangeTestTubes、OpenPillBottle、OrganizeStationery、PackBag、ZipUp、PaperCupStacking、StoreRacket、StackCups、PlugInEthernet、StackBowls、StoreEarphones、PackPhone、OrganizePencilCase、SyringeWaterTransfer。
- **B 档：VLA 优先（13）**：FruitCollection、PackDoll、FruitSorting、ColorArrangement、PlacePhotoFrame、OrganizeBookshelf、PickOutBatteries、OrganizeTools、FoldTowel、ArrangePlates、SpellRobot、ConveyorSorting、RemovePinnedNote。
- **C 档：低投入/观察**：单任务通道 `p_t≈0` 且失败在早期感知/抓取的任务。

DART 的边际收益主要在 A 档接触段和人为干扰轴（20%）；B 档主要受益于 RT-Contract 的 p99 降低，而不是伺服精度。

### 8.2 何时用 DART

| 场景 | 建议 |
|---|---|
| A 档、接触段、RTT 中低 | L0/L1；TPR + S2/S3 + DASD |
| A 档、RTT 高 | L2；PBVS + DASD；关闭 IBVS |
| B 档、语义为主 | L1/L2；保留 RT-Contract，减少 S3 |
| C 档、早期失败 | L3 基线；不投入 DART |
| 人为干扰 | S2 重定位 + L4 恢复；DASD 降速 |

### 8.3 提交节奏

1. **W0**：官方 WLA + API adapter + `pivot` 零回退 + CHUNK-SERVO 固定表基线；单任务跑通。
2. **W1**：WCET 微基准 + RT-Contract + 看门狗；不改变控制律，先降 p99。
3. **W2**：TPR + DASD；离线回放验证。
4. **W3**：STSM 小规模（2 family × 32 桶 × 64 候选 × 10 rollout）；单任务 A/B。
5. **W4**：全量 STSM + N 端口压力；G1–G7。
6. **W5**：全量干跑 32×10；G8–G10。
7. **W6**：提交；保留回滚开关。

若只允许一次提交：先交 CHUNK-SERVO 安全基线还是 DART，取决于 G4；没有 G4 通过，不交 DART。

### 8.4 成本/收益

| 方案 | 成本（估算） | 预期收益 | 建议 |
|---|---|---|---|
| CHUNK-SERVO 固定表 | 已有 | 基线 | 必做 |
| RT-Contract + TPR | 1–2 人周 | p99 降 20–40%；stale plan 误差降 50% | 主投，低风险 |
| STSM（小规模） | 1 GPU-day + 1 人周 | 阶段/增益排序改善；A 档 +0–3pp | 先验证 |
| STSM（全量） | 1–2 GPU-day + 2 人周 | A 档 +3–6pp；全局 +1–3pp | 过了 G2 再投 |
| 完整世界模型/从零训 | 8+ GPU 周 | 不确定 | 不做 |

收益算术：A 档 19 任务各 +5pp → `19/32×5≈+3.0pp`；若只有 10 个任务生效 → `+1.6pp`；p99 降低主要改善“结果可信度”和 timeout，不直接加成功率。**不要把设计目标当承诺。**

## 9. 风险与合规

### 9.1 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 + 固定表 | STSM 只离线生成，线上只用固定保守表 | 最低 | 保守首选 |
| C2 确定性控制器 + 参数表 | 伺服是几何/控制律；表是控制器参数；VLA 唯一学习模型 | 低；需说明 | 主推 |
| C3 同 checkpoint 特征 | 目标描述子用 VLA encoder | 低–中 | 需要强描述子时用 |

禁止：加载第二个学习策略/残差网络/独立视觉编码器做在线决策；在线更新 STSM；把 STSM 说成“小模型”。

### 9.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| **WCET/价值表与评测机不匹配** | 该做的阶段没做，或超时 | 目标容器实测；2× 余量；看门狗；admission；降级 |
| STSM 过拟合仿真 | 真机阶段排序失真 | 鲁棒认证；真实回放；保守前缀；只当先验 |
| Python GIL/GC | p99 抖动 | C++/pybind11；预分配；`gc.disable()`；独立进程 |
| N 端口 CPU/GPU 争用 | 全端口 p99 上升 | 每端口进程；CPU 亲和；EDF；admission；限批 |
| TPR 帧/TCP 约定不一致 | 动作偏移 | `example_env.py` 验证；手眼/工具坐标校准；零 pivot |
| `pivot_3..5` 语义不明 | 下身体动作错误 | 零 pivot 回退；只验证双臂；单任务通道 |
| 降速过多 | 180s 超时 | 只在接触/预接触降速；自由段恢复；超时前 L3 |
| 单模型解释 | 被判第二个模型 | C2 说明；表无权重；无在线学习；必要时 C1 |
| 评估噪声 | +1–2pp 假阳性 | 配对 A/B；bootstrap；320 trials SE≈2.4pp |
| 目标移动预测错误 | 伺服追错目标 | 协方差门控；置信度低不用预测；降增益 |
| 看门狗 abort 状态不一致 | 动作跳变 | 只在安全点 abort；返回上一完整阶段；限幅 |
| 端口 reset 不干净 | 跨 episode 污染 | 每端口独立进程；reset 清零 plan/goal/队列；G5 |

### 9.3 本轮最大风险

**STSM 的 WCET/价值表是在开发机和仿真里测的，而评测机的 CPU、Python GC、JPEG/msgpack、N 端口争用会让真实执行时间偏离表值；一旦偏离，anytime 调度会在最需要 IBVS 的接触段提前退化，DART 相对 CHUNK-SERVO 的收益就被吃掉。**

## 11. 一句话押注

**用仿真训练一张可审计的控制器参数表，用 WCET 预算和看门狗保证每次 `get_action` 在截止时间内返回 best-so-far，用 TPR 把异步 VLA plan 按时间重锚定，用 DASD 把开环漂移压回任务容差——在不新增学习模型、不改变固定 chunk 的前提下，让 CHUNK-SERVO 的 167ms 闭环在真实远程 API 上可预测地发生。**

**本轮最大风险一句话**：DART 的收益依赖一张在开发机上测得的 WCET/价值表；评测机只要慢 30%，anytime 调度就会在最需要 IBVS 的接触段提前退化，收益被吃掉。
