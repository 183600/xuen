# 第 46 轮（承接第 45 轮 v10；本轮灵感：避障控制 × 基线复现） · Control-Cert × Repro-Cert：控制诱导证书需求与可复现基线下的闭环避障认证（四层架构 v11）

> 承接第 45 轮 v10 Energy-Context-Depth。v10 解决了「感知可信度随能量-上下文动态变化」的问题，但仍停留在**感知侧**：P_t 只声明「我对自身位姿有把握」，安全谓词 φ^□(P_t) 仍按**静态碰撞检查**评估。隐含假设 H5：控制器理想、安全裕度静态、基线比较公平。两个新灵感词精确命中 H5：**避障控制**让安全从静态几何判断变成带反应延迟与刹车距离的**闭环动态约束**——位姿证书半径 r_t 会经控制器敏感度放大为对避障裕度的侵蚀，证书需求不再固定，而是由控制器**反向诱导**；**基线复现**则要求任何「证书感知避障更优」的声明必须在同一感知模态/能量预算/环境分布下重放 APF、DWA、MPC、CBF-QP、RL 基线，否则性能差不可归因于方法，甚至证书本身也必须能被独立重放。二者耦合出新问题：**如何把证书从『感知输出』升级为『控制契约』，并在可复现的匹配上下文中证明该契约带来的是真安全而非资源不对称**。

## 0. 直觉与动机

**灵感 1（避障控制 → 证书成为控制契约）**
直觉：避障不是「现在没碰」而是「保证来得及停」。控制器需要知道自己的状态估计有多差：若位姿证书半径 r_t 大于控制器可容忍的误差 r_req，那么再好的避障算法也只是在错误位姿上做正确的事。反过来，安全裕度函数 h_obs 对状态越敏感（L_h 越大），同样的 r_t 越危险。于是证书需求由控制器**反向计算**：r_req=(h_obs(x̂)-m_safe-ν·Δt_react)/L_h。只有 r_t ≤ r_req 才允许执行；否则收紧动作或 fail-closed。这把 v10 的「感知证书」真正接进了控制回路。

**灵感 2（基线复现 → 性能差必须可归因）**
直觉：若我们的方法偷偷开了深度相机而基线只用 RGB，赢是理所当然却毫无意义。可复现性不是「补实验」，而是**比较成立的前提**。定义上下文字段 c=(模态 m, 能量租约 ℓ_e, 环境分布 D, 控制器 κ, 种子)；复现缺口 δ_rep 与上下文失配 Δc 必须都小于阈值，比较才可采纳。更深一层，证书的共形校准、数据护照、随机种子也必须能独立重放——**证书本身是可复现的科学主张**。

**灵感 3（二者耦合 → 证书膨胀鲁棒 CBF 与可复现闭环审计）**
直觉：把位姿不确定性塞进控制屏障函数：h 在 P_t 上的最坏值约为 h(x̂)-L_h·r_t，导数项同理，于是鲁棒 CBF 的右端出现与 r_t 成正比的**证书膨胀项**。证书越松，约束越保守；证书越紧，动作越激进。这给出控制-证书的定量桥。再用可复现基线框架回答「这套保守是否值得」，避免用资源不对称换性能。

**耦合升级**：v10 四层上升为 v11。根信任层将新增 **Repro-Passport** π_rep，与既有能量/姿态租约并列；L1 几何层输出**方向性证书半径** r_t(θ)（沿障碍法向精确保鲜）；L2 上下文层保持预测职责但需为报告附带上下文护照；L3 CAR 守卫加入**控制可行性**（r_t ≤ r_req 且鲁棒 CBF）；L4 DCL 增加**控制临界样本**（近碰撞/高 L_h/刹车边界）与复现样本。

## 1. 形式化定义（增量：定义 54–57）

**定义 54（控制诱导证书需求）**
避障控制器 κ: X̂→U，安全裕度 h_obs(x)≥0 为到最近障碍的带符号距离。位姿证书 P_t 中心 x̂_t、半径 r_t=rad(P_t)。设 L_h=Lip(h_obs) 为 h_obs 对状态的 Lipschitz 常数，ν_max 为最大接近速度，Δt_react 为感知+控制+执行延迟上界，m_safe 为要求安全裕度。定义
r_req(t) = max(0, (h_obs(x̂_t) - m_safe - ν_max·Δt_react) / L_h).
**控制可行判据**：r_t ≤ r_req(t)。若 r_t > r_req 则控制器必须将动作投影到收紧安全集，若无解则 fail-closed。

**定义 55（证书膨胀鲁棒控制屏障）**
控制仿射系统 ẋ=f(x)+g(x)u，普通 CBF 约束 ḣ(x,u)+α(h_obs(x))≥0。对 x∈P_t，用 Lipschitz 展开得最坏值下界
min_{x∈P_t}[ḣ(x,u)+α h_obs(x)] ≥ ḣ(x̂,u)+α h_obs(x̂) - (L_ḣ+α L_h)·r_t.
故**证书膨胀鲁棒 CBF**为
ḣ(x̂,u)+α h_obs(x̂) ≥ (L_ḣ+α L_h)·r_t.
右端即证书膨胀项，与 r_t 成正比。若刹车动作 u_brake 仍使上式成立，则称证书在该时刻**控制足够**。

**定义 56（可复现缺口与匹配上下文）**
基线 B 在上下文 c_B=(m_B, ℓ_e,B, D_B, κ_B, seed_B) 报告指标 M_B，复现流程重放得 M_B^rep，度量距离 d。定义
可复现缺口 δ_rep(B)=d(M_B, M_B^rep)；
上下文失配 Δc=dist(c_proposed, c_B)，取模态/能量/环境/控制器四分量加权最大差。
**比较可采纳**：∀B，Δc(B) ≤ ε_c 且 δ_rep(B) ≤ ε_rep。否则性能差不得归因于方法。

**定义 57（复现护照与证书基准）**
复现护照 π_rep=(m, ℓ_e 快照, r_t 轨迹, κ 版本哈希, seed, 数据护照哈希, 校准切分哈希, 软硬件版本)。证书基准为四元组 (D, 协议, 指标, 审计器)。每次运行必须签发 π_rep；审计器可独立重放，未达标基线被打回复现，其数字不得进入主表。

## 2. 三大新增产出与既有 IP 升级

**IP-66 OACC（Obstacle-Avoidance Control Certifier）**
- 控制诱导证书需求 r_req 实时计算（h_obs, L_h, ν_max, Δt_react）
- 证书膨胀鲁棒 CBF-QP：约束右端含 (L_ḣ+αL_h)·r_t
- 证书-动作可行性检查与「收紧动作 / brake / fail-closed」状态机
- 方向性证书使用：沿障碍法向取 r_t(θ_obs) 而非各向同性上界

**IP-67 REPRO-HARNESS（Baseline Reproduction Harness）**
- 匹配上下文重放 APF / DWA / MPC / CBF-QP / RL 基线
- δ_rep 与 Δc 计算、可采纳性判定
- π_rep 签发与独立重放
- 反事实公平性检查：给基线同样模态/能量预算后再比较

**IP-68 CCR（Closed-loop Certificate & comparison Registrar）**
- 闭环违例搜索：控制诱导漂移、证书过期窗口内的 off-nominal 动作
- 证书膨胀项正确性审计：L_h/L_ḣ 的经验上界复核
- 基线复现红队：找隐藏资源不对称与上下文漂移

**既有 IP 升级**
IP-60 PSE：输出方向性 r_t(θ) 与协方差主轴，供沿障碍法向裁剪
IP-51 CAR：守卫加入 r_t ≤ r_req、鲁棒 CBF 可行性、π_rep 完整性检查
IP-61 DCL：采集效用加入控制临界度 criticality=L_h·ν，新增复现样本与 near-miss
IP-62 CCA：新增闭环证书膨胀审计、基线复现公平性审计、上下文漂移检测
IP-45 总线：新增 control-cert-demand / cbf-margin / robustness-inflation / repro-passport 话题

## 3. 算法骨架

OACC + CAR 每控制周期：
1. 读 x̂_t, r_t(θ), h_obs, ℓ_p, ℓ_e, π_rep
2. 计算 r_req(t)（沿障碍法向取方向性半径）
3. 若 r_t > r_req：投影动作到收紧安全集；无解则刹车→fail-closed
4. 解证书膨胀鲁棒 CBF-QP，得 u_t^*
5. 若 u_brake 使鲁棒 CBF 失效 → 证书控制不足，fail-closed
6. 记录 π_rep（模态 / 能量 / r_t 轨迹 / κ 哈希）

REPRO-HARNESS 离线/准在线运行：在匹配上下文下重放基线，算 δ_rep/Δc，签发 π_rep，主表只收可采纳基线。

## 4. 本轮最大风险

**一句话**：证书膨胀鲁棒 CBF 的安全性完全依赖 L_h 与 L_ḣ 的上界估计，一旦在透明/高光/弱纹理退化层低估敏感度（Lipschitz 常数偏小）或高估方向性半径，膨胀项不足会让「看似合法」的穿越动作通过，而失配上下文下的基线复现又会让「更优」结论既不可归因也不可证伪；因此必须以独立审计集强制复核 L_h/L_ḣ 经验上界并冻结匹配上下文协议。

## 2. 关键算法 伪代码

### IP-66 OACC
```
def required_radius(h_obs, xhat, L_h, nu_max, dt_react, m_safe):
    # 最坏位姿误差方向上的裕度侵蚀 + 反应窗口接近距离
    return max(0.0, (h_obs - m_safe - nu_max*dt_react) / max(L_h, EPS))

def robust_cbf_qp(xhat, u_nom, r_t, L_h, L_hdot, alpha, h_obs):
    # argmin ||u-u_nom||^2
    # s.t. hdot(xhat,u) + alpha*h_obs >= (L_hdot + alpha*L_h)*r_t
    #      u in U
    return solve_qp(xhat, u_nom, r_t, L_h, L_hdot, alpha, h_obs)

def oacc_step(xhat, r_t_dir, h_obs, L_h, L_hdot, ui, lease_e, rep):
    r_req = required_radius(h_obs, xhat, L_h, ui.nu_max, ui.dt_react, ui.m_safe)
    r_use = max(r_t_dir, ui.eps_iso)          # 方向性半径 + 各向同性下界
    u_nom = ui.nominal(xhat)
    if r_use > r_req:
        u = tighten(u_nom, r_use, r_req)      # 投影到收紧安全集
        if u is None:
            return brake_then(FailClosed('control_cert'))
    else:
        u = u_nom
    u = robust_cbf_qp(xhat, u, r_use, L_h, L_hdot, ui.alpha, h_obs)
    if not cbf_ok(u_brake, r_use, L_h, L_hdot, ui.alpha, h_obs):
        return FailClosed('cert_control_insufficient')
    sign_passport(rep, xhat, r_use, u, lease_e)
    return u
```

### IP-67 REPRO-HARNESS
```
def repro_gap(M, M_rep, d):
    return d(M, M_rep)

def context_mismatch(c1, c2, W):
    # 四分量：模态 m / 能量 ℓ_e / 环境 D / 控制器 κ
    return max(W[k] * dist(c1[k], c2[k]) for k in ('m','energy','env','kappa'))

def admissible_baseline(B, c_proposed, eps_c, eps_rep, harness):
    M_rep, c_B = harness.rerun(B)             # 匹配模态/能量/环境/种子
    drep = repro_gap(B.M, M_rep, B.metric)
    dc = context_mismatch(c_proposed, c_B, W)
    return (dc <= eps_c and drep <= eps_rep), dict(drep=drep, dc=dc)

def repro_passport(run):
    return dict(m=run.m, energy=run.lease_e.snapshot(), r_t=run.r_t_trace,
                kappa_hash=hash(run.controller), seed=run.seed,
                data_hash=run.data.passport_hash, calib_hash=run.calib.hash,
                env=run.env_hash, hw=run.hw_version)
```

### IP-68 CCR 审计
```
def audit_inflation(audit_set, L_h, L_hdot):
    # 经验上界复核：真实 h 差不得超过声称 Lipschitz * 状态距离
    viol = 0
    for (x, y, hx, hy, dhx, dhy) in audit_set:
        if abs(hx - hy) > L_h * norm(x - y): viol += 1
        elif abs(dhx - dhy) > L_hdot * norm(x - y): viol += 1
    return viol / len(audit_set)              # 必须为 0

def redteam_fairness(baselines, c_proposed, eps_c):
    # 上下文未匹配的基线不可采纳
    return [B for B in baselines
            if context_mismatch(c_proposed, B.c, W) > eps_c]
```

def car_guard_v7(e, x, cert, persona, lease_p, lease_e, rep, u, t):
    if (not pose_lease_valid(lease_p, t)
            or not energy_lease_valid(lease_e, t, E_min(e))
            or not rep_complete(rep)):

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| OACC r_req | O(1) | O(1) | r_t≤r_req ⇒ 反应窗口内 h_obs≥m_safe（Lipschitz 上界成立时） |
| 鲁棒 CBF-QP | O(n^3) 每周期 | O(n^2) | 证书膨胀 ⇒ P_t 内最坏 CBF 约束满足 |
| Repro-Harness | O(#baseline·T_run) 离线 | O(#baseline) | Δc≤ε_c ∧ δ_rep≤ε_rep ⇒ 性能差可归因 |
| CCR 膨胀审计 | O(N_audit) | O(N_audit) | L_h/L_ḣ 经验违例率=0 ⇒ 上界可信 |
| CAR v7 | O(1) | - | 租约/护照/控制可行性任一失效 ⇒ fail-closed |

**正确性定理（闭环避障）**：若 (i) r_t ≤ r_req(t)，(ii) L_h、L_ḣ 为经审计集验证的真实上界，(iii) 鲁棒 CBF 对 u 与 u_brake 均可行，(iv) 姿态/能量租约与 π_rep 有效，则闭环系统在反应窗口 Δt_react 内保持 φ_obs，且无证书诱导的穿越行为；若任一条件失效则进入 fail-closed。

**比较定理（可归因性）**：若 ∀ 基线 B 满足 Δc(B)≤ε_c 且 δ_rep(B)≤ε_rep，则主表中本文方法与基线的性能差可归因于方法本身，而非感知模态、能量预算、环境或控制器的资源不对称。

## 4. 实验设计 E109–E115

| 实验 | 指标 | 门槛 |
|---|---|---|
| E109 控制诱导需求保守性 | 无谓刹车率；必要 fail-closed 触发率；闭环碰撞 | 无谓刹车 <5%；0 碰撞 |
| E110 方向性 vs 各向同性半径 | 沿障碍法向 rad 缩减；窄通道通过率 | rad 降 ≥25%；通过率 ≥ 各向同性 |
| E111 Lipschitz 上界审计 | L_h/L_ḣ 经验违例率；膨胀不足导致的危险动作 | 违例 0；危险动作 0 |
| E112 基线复现（APF/DWA/MPC/CBF-QP/RL） | δ_rep；Δc；可采纳基线数 | δ_rep≤ε_rep；Δc≤ε_c；≥5 条 |
| E113 匹配上下文下证书感知 vs 基线 | 成功率；碰撞率；能耗；干预次数 | 成功≥基线；碰撞 0；能耗不劣于基线 |
| E114 闭环 100h | 碰撞；fail-closed 次数；上下文漂移 | 0 碰撞；漂移≤阈值 |
| E115 可复现性 | 跨种子方差；π_rep 重放一致率 | 方差≤阈值；一致率 ≥99% |

回退：E111 上界审计违例 → 放大 L_h/L_ḣ 保守化并重标定；E112 复现不达标 → 主表只报可复现基线与自消融；E109 fail-closed/无谓刹车过多 → 先做 m_safe 与 Δt_react 敏感性分析，再决定放宽；E113 无优势 → 回退「控制-证书」仅作安全守卫、不作性能卖点。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| L_h/L_ḣ 低估导致膨胀不足、伪安全穿越 | 高 | 独立审计集经验上界 + 保守放大 + 在线残差监测 |
| 方向性半径估计偏乐观 | 高 | 沿障碍法向取保守分位；各向同性能量上界作回退 |
| 基线上下文无法匹配导致比较不公 | 高 | 主动为基线补齐模态/能量预算；不达标基线明示不可采纳 |
| 证书膨胀导致过度 fail-closed / 可用性下降 | 中 | 收紧动作优先于刹车；阈值敏感性实验 |
| 复现计算成本高 | 中 | 缓存复现结果 + 版本哈希失效重跑 |
| 控制器敏感度模型随负载漂移 | 中 | 在线辨识 L_h/L_ḣ 并接入 CAR 动态阈值 |

## 6. 本轮最大风险

**一句话**：证书膨胀鲁棒 CBF 的安全性完全押在 L_h/L_ḣ 的上界与方向性半径估计上，一旦在透明/高光/弱纹理退化层低估敏感度，膨胀项不足会让「看似合法」的穿越动作通过，而失配上下文下的基线复现又会让「更优」结论既不可归因也不可证伪；因此必须以独立审计集强制复核 L_h/L_ḣ 经验上界，并冻结匹配上下文协议。
