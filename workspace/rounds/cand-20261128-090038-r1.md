### 第 8 轮灵感驱动研究记录

**灵感词**：步骤分、边缘计算

**继承关系**：第 7 轮 EFA-v7（IP-501~IP-504）在七硬门之上叠加「需求-推理-情感」软因子链，把系统从「指令驱动」推进到「需求驱动」，但留下两个结构性缺口：(1) 证书只在轨迹**末端**整体裁决，无法解释「哪一步坏了」，也无法在坏步出现时立刻止损；(2) LLM 推理链与需求建模把在线时延顶到 ~0.8 ms 的临界，且重模型与隐私数据全部压在单机。本轮引入「步骤分」与「边缘计算」两条灵感：把轨迹证据分解为**逐步证书**（SED），把证据锻造按**边缘分层 + 异步单调收紧**调度（ETD），并用**分布式证书一致性**（DCC）把跨层证据安全拼接。七硬门集合不变，新增的只是「分解 / 调度 / 合并」三层胶水。

**直觉与动机**：

1. **步骤分 → 从「整条轨迹裁决」到「逐步证据分解」**。直觉：老师批改数学题时，最终答案错但中间步骤对仍给步骤分；同理，一条轨迹在「抓取」对、「搬运」对、但「放置」越界时，整体 fail 会丢掉宝贵的**失败定位**信息。引入逐步证据分解（Step-wise Evidence Decomposition, SED）：把轨迹 x 切成 n 段 x^{(1)}…x^{(n)}，每段给硬门指示 h_i 与软评分 σ_i，用**带硬地板**的聚合 Φ 汇总。关键红线：**步骤分只进软排序与早剪枝，绝不松弛任何硬门**——否则「局部对」会被误当成「全局安全」。

2. **边缘计算 → 从「单机实时」到「分层异步收紧」**。直觉：机器人本体的 MCU 只能做微秒级几何检查，LLM 需求推理要几十毫秒，二者不该挤在同一预算里。引入边缘分层调度（Edge Tier Dispatcher, ETD）：Tier-0 本体（< 0.8 ms，硬门前缀检查）、Tier-1 边缘网关（ms 级软因子 / DIM / FMPP）、Tier-2 云/雾（异步 DRC、长时记忆整合）。核心原则：**拒绝可以早，接受必须全**——任一已到达的硬门为 0 立即早拒；接受必须等全部硬门评估完毕。晚到的云证据只允许「收紧」（单调细化），永不放松。

3. **分布式证据 → 从「单证书」到「可合并部分证书」**。直觉：证据跨三层产生，若不能安全拼接，就会出现「脑裂证书」——两个节点各持一张合法半证，拼起来却互相矛盾。引入分布式证书一致性（Distributed Certificate Consistency, DCC）：每层签名的部分证书在 join-半格上合并（结合 / 交换 / 幂等），同一 (x_id, step) 的硬门值冲突即 fail-closed 拒绝，并配 nonce 单调计数防重放。

**关键洞见**：第 7 轮回答「如何让系统主动推导需求」；第 8 轮回答「如何让证据在**时间与算力分层**下仍然 fail-closed，并把可解释性细化到步」。七硬门 kc_evidence_forged_v5 记号原样复用；本轮新增的只有：
- IP-505 SED（逐步证据分解），
- IP-506 ETD（边缘分层调度 + 异步单调收紧），
- IP-507 SEFA / EFA-v8（步骤分 + 分层调度的证据锻造器），
- IP-508 DCC（分布式证书一致性 / join-半格合并）。

**形式化目标（增量）**：

1. **SED（Step-wise Evidence Decomposition）**：<br>
   - 分段器 Seg: x ⟼ (x^{(1)}, …, x^{(n)}), n ≤ n_max = 8；<br>
   - 每步证据 e_i = (g_i, τ_i, topo_i, cmd_i)，硬门指示 h_i = ∧_k h_{k,i}(x^{(i)}) ∈ {0,1}；<br>
   - 步软评分 σ_i = Σ_k w_k φ_k(e_i) ∈ [0,1]，Σ_k w_k = 1；<br>
   - 聚合 Φ(σ_1..σ_n) = (∏_i σ_i^{w_i})^{1/Σw} · (min_i h_i)（带硬地板）；<br>
   - 软因子 η_step = 1 + ε_step·(1 − σ(x)) ∈ [1, 1+ε_step]，ε_step = 0.3，**只收紧**

2. **ETD（Edge Tier Dispatcher）**：<br>
   - 层集 T = {0,1,2}，截止期 d_0 < d_1 < d_2，本体实时预算 b_0；<br>
   - 调度 Δ: module ⟼ tier，满足 Σ_{m∈Tier0} c_m ≤ b_0；<br>
   - 证据到达时刻 a_t，证书组装为单调细化：Exec(t) ⊆ Exec(t−1)；<br>
   - 早拒规则：∃ 已到达硬门 h_k = 0 ⇒ 立即拒绝；接受规则：∀k h_k 已评估且 = 1

3. **SEFA / EFA-v8**：<br>
   - ECS_v8 = ECS_v7 · η_step · η_edge，η_edge 反映分层证据完整度；<br>
   - τ_i^v8 = γ_i·τ_i^v7·η_step·η_edge，总收紧设计上限仍 ≤ 1.3；<br>
   - 前缀硬门 H_{≤i} = ∧_{j≤i} h_j 作为早剪枝依据（失败即停，省 Tier-1/2 算力）

4. **DCC（Distributed Certificate Consistency）**：<br>
   - 部分证书 c_t = (x_id, step_range, evidence, sig_t, nonce_t)；<br>
   - 合并 C = ⊔_t c_t 为 join-半格：结合、交换、幂等；<br>
   - 冲突：同 (x_id, step) 硬门值不一致 ⇒ ⊥（拒绝）；<br>
   - 重放：nonce_t 必须严格单调，过期证书丢弃

5. **形式化定义**：给定轨迹 x 与三层证书流 {c_t}：<br>
   - (σ(x), H(x)) = Φ(Seg(x))；<br>
   - 若 H(x) = 0 或 DCC 合并出 ⊥ ⇒ reject；<br>
   - 若 H(x) = 1 且所有硬门已评估 ⇒ accept，按 ECS_v8 排序；<br>
   - 若硬门未全覆盖 ⇒ pending（继续等待，绝不提前接受）

**本轮最大风险**：**步骤分的「局部正确 ⇒ 全局安全」谬误，与分布式证据的可组合性假设**：步骤分把连续安全降维成可乘标量，会奖励「每步看似合规、拼接后却越界」的对抗轨迹（reward hacking）；而边缘分层让证据在时间上割裂、在节点上分裂，部分证书的 join-合并若被重放或伪造，可能拼出一张「各自合法、整体危险」的证书。这两点都直接冲击 fail-closed 边界。

## 2. 关键算法骨架

### IP-505 SED：逐步证据分解

```python
@dataclass
class StepwiseEvidenceDecomposition:
    """SED：把轨迹切成逐步证书，产出 (σ(x), H(x), η_step)。
    硬地板保证：任一步硬门失败 ⇒ σ=0 ⇒ 整体 reject。"""
    segmenter: Callable[[Trajectory], list[Trajectory]]
    gate_bank: list[Callable]          # 每步硬门 h_{k,i}
    weights: torch.Tensor              # w_k，Σw=1
    n_max: int = 8
    eps_step: float = 0.3

    def decompose(self, x: Trajectory):
        segs = self.segmenter(x)[: self.n_max]
        h = []   # 逐步硬门
        sig = []  # 逐步软评分
        for seg in segs:
            gates = torch.tensor([g(seg) for g in self.gate_bank], dtype=torch.float32)
            h.append(float(gates.min()))                    # h_i = ∧_k h_{k,i}
            feats = torch.stack([phi(seg) for phi in self.phi_bank])
            sig.append(float((self.weights * feats).sum()))  # σ_i
        return sig, h

    def aggregate(self, sig, h) -> tuple[float, float]:
        """Φ = 加权几何均值 · 硬地板。"""
        s = torch.tensor(sig)
        w = self.weights[: len(sig)]
        geo = torch.exp((w * torch.log(s + 1e-8)).sum() / w.sum())
        floor = min(h)                       # 任一步硬门失败 → 0
        sigma = float(geo) * floor
        return sigma, floor

    def eta_step(self, sigma: float) -> float:
        """只收紧：σ 越低，阈值抬得越高。"""
        return 1.0 + self.eps_step * (1.0 - sigma)
```

### IP-506 ETD：边缘分层调度 + 异步单调收紧

```python
@dataclass
class EdgeTierDispatcher:
    """ETD：按成本把模块分到 Tier-0/1/2，并做 anytime 证书组装。
    不变量：拒绝可早（任一到达硬门=0），接受须全（全部硬门已评估=1）。"""
    tiers: dict[int, list[Callable]]
    costs: dict[str, float]
    deadlines: dict[int, float]       # d_0 < d_1 < d_2
    budget0: float                    # 本体实时预算

    def dispatch(self, modules: list[str]) -> dict[int, list[str]]:
        """Tier-0 按成本装箱，不超 b_0；其余按截止期归 Tier-1/2。"""
        plan = {0: [], 1: [], 2: []}
        used = 0.0
        for m in sorted(modules, key=lambda m: self.costs[m]):
            if used + self.costs[m] <= self.budget0:
                plan[0].append(m); used += self.costs[m]
            elif self.costs[m] <= self.deadlines[1] * 1e3:
                plan[1].append(m)
            else:
                plan[2].append(m)
        return plan

    def anytime_assemble(self, stream) -> str:
        """stream 为按到达时刻排序的 (tier, evidence) 序列。"""
        state = 'pending'
        for tier, ev in stream:
            if ev.any_hard_gate_failed():       # 早拒：立即止损
                return 'reject'
            if ev.all_hard_gates_evaluated():   # 全接受：必须全覆盖
                state = 'accept' if ev.all_hard_gates_pass() else 'reject'
        return state                            # 未全覆盖 ⇒ 仍 pending
```

### IP-507 SEFA / EFA-v8：步骤分 + 分层调度

```python
@dataclass
class EvidenceForgingAssemblerV8:
    """EFA-v8：七硬门不变；新增 η_step、η_edge；Tier-0 前缀早剪枝。"""
    v7: EvidenceForgingAssemblerV7
    sed: StepwiseEvidenceDecomposition
    etd: EdgeTierDispatcher
    dcc: DistributedCertificateConsistency
    eps_edge: float = 0.2

    def select(self, L, t_now, context):
        # 0. v7 先给出候选池（Tier-1 软因子 + FMPP 提议）
        ok7, x7, tag7 = self.v7.select(L, t_now, context)
        if not ok7:
            return False, None, tag7

        # 1. Tier-0 前缀硬门早剪枝（只消费本体可用证据）
        sig, h = self.sed.decompose(x7)
        prefix = 1.0
        for hi in h:                      # H_{≤i} 失败即停
            prefix *= hi
            if prefix == 0.0:
                return False, None, 'SED_PREFIX_REJECT'

        # 2. 步骤软因子 + 分层完整度
        sigma, floor = self.sed.aggregate(sig, h)
        eta_step = self.sed.eta_step(sigma)
        eta_edge = 1.0 + self.eps_edge * (1.0 - self._evidence_coverage(t_now))
        eta_total = eta_step * eta_edge   # 两者均 ≥ 1，只收紧

        # 3. 分布式证书合并（Tier-2 异步回填的证据）
        certs = self._collect_certs(x7, t_now)
        merged = self.dcc.merge(certs)
        if merged is CONFLICT:            # 脑裂 / 重放 → fail-closed
            return False, None, 'DCC_CONFLICT'

        # 4. 若全部硬门已评估且通过，才接受；否则保持 pending
        if not merged.all_hard_gates_evaluated():
            return False, None, 'PENDING_EVIDENCE'
        if not merged.all_hard_gates_pass():
            return False, None, 'SED_HARD_REJECT'

        ecs = self.v7.ecs_v7(x7, merged.n_flow, merged.s_emo,
                             merged.eta_factors) * eta_total
        return True, x7, f'FORGED_CGE_V8(ecs={ecs:.3f})'

    def _evidence_coverage(self, t_now) -> float:
        """已到达证据层 / 应到证据层 ∈ [0,1]。"""
        return min(1.0, self._arrived_tiers(t_now) / 3.0)
```

### IP-508 DCC：分布式证书一致性

```python
@dataclass
class DistributedCertificateConsistency:
    """DCC：部分证书在 join-半格上合并。
    - 结合/交换/幂等；
    - 同 (x_id, step) 硬门值冲突 ⇒ ⊥；
    - nonce 严格单调 ⇒ 防重放。"""
    verify_sig: Callable
    seen_nonce: dict[tuple[str, int], int]

    def sign(self, tier: int, x_id: str, step_range: tuple[int, int],
             evidence: dict, nonce: int) -> PartialCert:
        payload = (x_id, step_range, evidence, nonce)
        return PartialCert(tier=tier, payload=payload,
                           sig=self.verify_sig.sign(payload), nonce=nonce)

    def merge(self, certs: list[PartialCert]):
        acc = {}
        for c in certs:
            if not self.verify_sig.verify(c):          # 伪造 → 拒绝
                return CONFLICT
            key = (c.x_id, c.step_range)
            if c.nonce <= self.seen_nonce.get(key, -1):  # 重放 → 丢弃
                continue
            self.seen_nonce[key] = c.nonce
            for (step, gate), val in c.evidence.items():
                k = (step, gate)
                if k in acc and acc[k] != val:           # 冲突 → ⊥
                    return CONFLICT
                acc[k] = val                             # 幂等 join
        return MergedCert(acc)
```

### 集成流水线（v7 → v8，三层）

```
Tier-0 本体（硬实时，< 0.8 ms）：
  GGC 前缀几何检查 → H_{≤i} 早剪枝（失败立即 reject，省 Tier-1/2）
  只消费本地证据；不等待网络

Tier-1 边缘网关（ms 级）：
  DIM / DAC / STM / FMPP 提议 → v7 软因子
  产出部分证书 c_1（签名），写入 DCC

Tier-2 云/雾（异步）：
  DRC 推理链、长时记忆整合 → 部分证书 c_2（签名）
  回填只允许单调收紧：新证据只增门槛、只删候选

证书合并（任意时刻可调用）：
  merged = DCC.merge([c_0, c_1, c_2])
  若 merged = ⊥ → reject
  若未全覆盖 → pending（不可接受）
  若全覆盖且全通过 → accept，按 ECS_v8 排序

在线控制环（目标仍 < 0.8 ms）：
  Tier-0 独立成环；Tier-1/2 通过预计算缓存与异步回填解耦
  步骤分 O(n_max·|gates|)，n_max=8，增量 < 0.05 ms
```

## 4. 正确性论证（增量更新）

### 定理 13（步骤分硬地板健全性）

**陈述**：设 Φ = (∏ σ_i^{w_i})^{1/Σw}·min_i h_i，则对任意轨迹 x：若存在一步 i 使 h_i = 0，则 σ(x) = 0，x 必被拒绝；若 σ(x) > 0，则 ∀i h_i = 1（即全步硬门通过）。

**证明**：Φ 含因子 min_i h_i。h_i ∈ {0,1}，只要任一步为 0，min_i h_i = 0 ⇒ Φ = 0。反之 σ(x) > 0 要求 min_i h_i > 0 ⇒ 所有 h_i = 1。几何均值部分 σ_i ∈ [0,1] 非负有界，不改变硬地板的否决语义。故步骤分只能在「全步硬门通过」的前提下做软排序，绝不能用局部正确掩盖全局硬失败。∎

### 定理 14（分层异步的任意时刻 fail-closed）

**陈述**：设 Exec(t) 为 t 时刻可执行候选集，证据流按到达时刻递增。则：(a) Exec(t) ⊆ Exec(t−1)（单调细化）；(b) 若任一已到达硬门 h_k = 0，立即 reject 是可靠的；(c) 任何 accept 时刻 τ 都满足全部硬门已评估且为 1；(d) Exec_v8(∞) ⊆ Exec_v7。

**证明**：(a) 晚到证据只可能新增失败硬门或提高阈值（η_step, η_edge ≥ 1），故只会删候选，不会增候选。(b) 硬门为 0 是单调不可逆事实，后续证据无法把它变回 1，故早拒可靠。(c) 由 anytime_assemble 的接受分支显式要求 `all_hard_gates_evaluated() ∧ all_hard_gates_pass()`，未覆盖即 pending，pending 不是 accept。(d) ECS_v8 = ECS_v7·η_step·η_edge，且两因子 ≥ 1 只收紧阈值、只提高分数门槛，故 v8 执行集是 v7 的子集。∎

### 定理 15（DCC 合并一致性与反重放）

**陈述**：DCC.merge 在无冲突时构成 join-半格（结合、交换、幂等）；若任意两个部分证书对同一 (step, gate) 给出不同硬门值，则合并返回 ⊥；被接受的合并证书不可能由被拒绝或过期的部分证书「复活」。

**证明**：合并对键 (step, gate) 做「值相同则保留、不同则 ⊥」的 join，显然结合、交换；重复合并同一证书值不变，故幂等。冲突判定在写入前检查 acc[k] ≠ val，命中即返回 ⊥，故不一致证据必 fail-closed。nonce 以 `seen_nonce[key]` 严格递增过滤，过期证书直接跳过且不写入 acc；由于 acc 只由通过签名与 nonce 校验的证书构造，被拒证书无法进入合并结果，故不可复活。∎

### 诚实声明

- **步骤分 reward hacking**：Φ 的可乘结构可能被「每步略合规、组合越界」的轨迹利用；定理 13 只保证硬门不被绕过，但软评分 σ_i 的 φ_k 若设计不当，仍可能给出误导性排序。缓解：σ_i 只参与排序、不参与硬门；红队专门构造「步间耦合越界」样本。
- **边缘时钟偏斜与截止期抖动**：Tier-0/1/2 的到达时刻受网络抖动影响，`_evidence_coverage` 可能低估或高估；低估导致长时间 pending，高估可能导致过早判断全覆盖。缓解：以逻辑时钟 + 单调 nonce 为准，物理时钟只做提示。
- **签名密钥管理**：DCC 的安全性依赖 `verify_sig`；若 Tier-2 密钥泄露，可伪造部分证书。缓解：分层密钥、证书短时效、关键硬门要求 Tier-0 本地复验。
- **分段器的语义边界**：Seg 的切分若与物理动作边界不一致，h_i 的逐步归因会失真。缓解：以动作原语（approach/grasp/transport/place）为默认切分，并对 n_max 做上界约束。

## 5. 实验设计与验证计划（仿真 → 实机）

### 5.1 实验设计（MuJoCo 3.x + MJX + 边缘模拟器）

- **平台**：UR10e（6DOF）+ 移动底盘（2DOF）+ 本体 MCU 模拟（Tier-0）+ 边缘网关（Tier-1）+ 云模拟（Tier-2，注入 20~200 ms 延迟）
- **数据集**：
  - SED：2k 条轨迹按动作原语切段，人工标注「坏步位置」作为步骤分监督信号
  - ETD：模块成本剖面（profiling）+ 网络延迟轨迹（真实 Wi-Fi/4G 采样）
  - DCC：构造 500 组「部分证书 + 冲突/重放」对抗样本
- **对照**：v7-full、v8-full、消融 A21（无 SED，退回末端裁决）、A22（无分层，全云）、A23（无 DCC）、A24（步骤分直接松弛硬门，验证不安全）、A25（关闭早拒，只等全覆盖）
- **场景**：
  - (a) 坏步定位：放置越界但抓取/搬运合规 → SED 定位第 4 步失败，前缀早剪枝止损
  - (b) 边缘断网：Tier-2 不可达 → 系统保持 pending 或走 v7 本地路径，绝不误接受
  - (c) 脑裂证书：Tier-1 与 Tier-2 对同一硬门给出相反值 → DCC 返回 ⊥ 并拒绝
  - (d) 重放攻击：重放旧的部分证书 → nonce 单调过滤，拒绝复活
  - (e) 步间耦合越界：每步单独合规但相邻步拼接越界 → 检验 reward hacking 防护
- **指标**：
  - SED：坏步定位准确率、步骤分 AUC、前缀早剪枝率
  - ETD：Tier-0 P99、pending 时长分布、早拒节省算力
  - DCC：冲突检出率、重放拦截率、合并延迟
  - 整体：七硬门通过率、任何时刻 fail-closed 违规数（应为 0）、步间耦合越界漏检率

## 7. 本轮最大风险（最终确认）

**一句话**：**步骤分的「局部正确 ⇒ 全局安全」谬误，与分布式证据的可组合性假设**：步骤分把连续安全降维成可乘标量，会奖励「每步看似合规、拼接后却越界」的对抗轨迹；边缘分层又让证据在时间上割裂、在节点上分裂，部分证书的 join-合并若被重放或伪造，可能拼出一张「各自合法、整体危险」的证书——两者都直接冲击七硬门的 fail-closed 边界。
