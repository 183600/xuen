# 第 44 轮（新循环第 4 轮） · Handoff-Cert × Dependability-Cert：把「控制权交接」与「可靠性衰减」纳入可验证证书闭环（四层架构 v9）

> 承接第 43 轮 v20（Persona-Cert × Concurrent-Cert）。v20 自陈最大风险是「共形只保边际覆盖 + 多用户契约求交为空」，但它仍压着两个更深的单点假设：**(H3) 人只是环境扰动或约束，而不是会延迟、会失效、会疲劳的「冗余子系统」**——v20 把人的意图做成共形集合，却默认「需要人接管时人一定接得住」；**(H4) 可靠性 = 安全性**——v20 用 soundness 衡量一切，但一个永远安全停机的系统，可靠性（可用性、任务完成率、可维护性）为零。本轮灵感词「人机协作」「可靠性」精确命中这两点：**人机协作**迫使我们把控制权做成显式、可交接、可回滚的一等状态，并把「接管延迟」提升为安全关键变量；**可靠性**迫使我们从「不出事」升级为「长期不出事且还能干活」，用可靠性框图、共因失效、退化阶梯与可靠性预算来度量。二者耦合处是本轮真正的新问题：人机冗余可能被共享感知导致的**共因失效**同时击穿，而可靠性预算优化可能把「安全但不可用」当成最优解。

## 0. 直觉与动机

**灵感 1（人机协作 → 控制权不是布尔开关，而是带证书的连续状态）**：直觉上，「人机协作」常被写成「人下指令、机器执行」或「机器求助、人接管」，仿佛控制权是一个瞬时布尔量。真实交接却是一段危险时间窗：人可能没注意、没就位、误解意图；机器可能在人未接稳时已放手；最坏情况出现「两个主人都以为对方在开」或「谁都没在开」。因此把控制权形式化为带租约的状态 α，交接必须是**原子**的（不存在无人负责窗口）、**可回滚**的（握手超时回到原主）、**有活性**的（不会无限来回抢权），且交接全程被 safe-hold 证书覆盖。一句话：**接管不是免费事件，而是一段必须持证的时间窗。**

**灵感 2（可靠性 → 是安全的对偶约束，不是同义词）**：直觉上，「永远停在原地」是最安全的策略，却也是最不可靠的策略。可靠性工程关心长期可用、可完成、可维护；安全工程关心不出不可接受事件。二者天然张力：最大化安全会收缩可用域，最大化可用会逼近安全边界。于是定义**可信性四元组** D=(safety, liveness, availability, maintainability)，并引入**可靠性预算 ρ** 与**可用性下限 A_min**：不允许用「安全但不可用」冒充成功。更要承认人是**既冗余又易错**的部件——人可以作为并行监控者提升冗余，也可能与机器共享同一感知而同时失效（共因失效），把纸面冗余变成纸面幻觉。

**灵感 3（耦合 → 共因失效 + 交接抖动是可靠性真正的杀手）**：共享感知、共享地图、共享心智模型让人与机器「一起错」；交接死锁（都不敢接）与交接抖动（来回抢权）则把可用性打成碎片。必须显式建模：用 β-factor 共因模型审计「人机独立」这一默认假设；用 dwell-time + 滞回抑制抖动；用交接活性证明排除死锁。可靠性由此不是事后统计，而是可被证书约束、可被仿真对抗验证的一等目标。

**耦合升级**：SAC（共享控制权证书）把每一次交接编译成带前后置条件、原子性、可回滚与活性的协议；DEP（可信性引擎）维护可靠性预算、共因失效模型与单调退化阶梯；HOV（交接验证器）在仿真中注入接管延迟、共因失效与反复交接，把反例回灌 CKB/SCV。四层架构由 v8 的「人格契约层 + 并发证书层」升级为 v9 的「仿真-检索-边缘飞轮 + 人格契约层 + 并发证书层 + 共享控制权/可信性层」。

## 1. 形式化定义（增量：定义 44–49）

**定义 44（共享控制权状态与联合动作）**：控制权 α∈[0,1]（或离散级 {autonomous, assisted, shared, teleop, manual}），联合动作 a=(a_r, a_h, α)，其中 a_r 为机器动作、a_h 为人动作，仲裁函数 Arb:(α, a_r, a_h)→a。要求**单一主控不变式**：任一时刻或存在唯一主控，或 α 落入显式共享包络 E_shared（其中人机动作都被证书约束）。**命题**：若每个主控在其证书域内动作且共享包络被证书覆盖，则联合动作不破坏 I。

**定义 45（可验证交接证书）**：交接 H=(C_i→C_j, φ, P_ready, S_hold, Abort, δ_dwell)。其中 φ 触发条件，P_ready 为接任方就绪谓词（经校准），S_hold 为过渡期 safe-hold 证书，Abort 为超时回滚协议，δ_dwell 为最小驻留时间。H 可验证当且仅当：
(1) **安全集重叠**：过渡窗 [t, t+Δ] 内 C_i 与 C_j 的认证安全集交集非空；
(2) **就绪可信**：P_ready 的置信度 ≥ 1−α_ready（校准）；
(3) **原子性**：不存在无主控窗口，否则 S_hold 必须覆盖该窗口；
(4) **可回滚**：Abort 有界时间回到 C_i 且保持 I；
(5) **活性**：在 δ_dwell 滞回下，交接序列最终进入稳定主控，无死锁、无无限抖动。
**定理（交接保 sound）**：若 (1)(2)(3)(4) 成立且 S_hold sound，则任意交接点 I 保持；若另加 (5)，则交接不会以牺牲可用性换取安全。

**定义 46（接管可靠性与共形前置时间）**：接管延迟 T_h 为人从被请求到真实掌握控制的时间随机变量。用分层共形给出上界 T_h^α，满足 P(T_h ≤ T_h^α) ≥ 1−α。机器在交接请求后须维持 safe-hold 至少 L = T_h^α + ε 的**前置时间**。**命题**：若剩余 safe-hold 时长 < L，则必须在更早时刻请求接管，或改走自动回退（退化阶梯），绝不假设人「立刻就到」。这把人机协作的时序可靠性变成可计算约束。

**定义 47（可信性四元组与共因失效）**：D = (R_safety, R_liveness, A_availability, M_maintainability)。人机系统按可靠性框图串并联组合；对共享部件集合 S_shared，采用 β-factor 共因模型：R_sys = (1−β)·R_ind + β·R_cc，β 由 S_shared 上的共因暴露度给出。**独立性证书**：只有当 β ≤ β_max 且共享部件被显式列举时，才允许宣称「人机冗余」。**可信性偏序**：D1 ⪯ D2 当且仅当四个分量均不劣；系统不得以牺牲 safety 换取 A 的提升，且 A 必须 ≥ A_min。

**定义 48（可靠性预算与单调退化阶梯）**：可靠性预算 ρ(t)≥0 随运行消耗；退化阶梯 R0（共享自主）≻R1（辅助）≻R2（自主回退）≻R3（safe-hold）≻R4（最小风险状态 MRC）。每级有消耗率与最低预算门槛。**单调性**：ρ 不足时只允许下降一级；任何上升级必须重新持证（定义 45）。**命题**：若每级证书与门槛 sound，则预算耗尽时的强制下降仍在 I 内，且不会跳级造成状态跳变。

**定义 49（信任校准与误用）**：信任估计 τ_trust 与实际可信性 R_sys 的偏差 g = τ_trust − R_sys。**过度信任**（g>δ）导致人脱离监控、接管更慢；**信任不足**（g<−δ）导致系统被弃用、可用性下降。协作策略须满足 |g| ≤ δ_trust，并通过解释、告警粒度与经验数据在线校准。**注**：这把「可靠性」从纯机器指标扩展为「人机联合系统的可信性」。

## 2. 三大新增产出与既有 IP 升级

### 2.1 IP-60 SHARED-AUTHORITY-CERTIFICATE（共享控制权证书 SAC）
1. **控制权状态机**：单一主控不变式 + 共享包络 + 原子交接；任何时刻可回答「谁在负责」。
2. **交接证书编译**：触发条件、就绪谓词、safe-hold、回滚、dwell 滞回一次编译成可检查契约。
3. **共形前置时间**：按 persona 校准 T_h^α，动态计算交接请求提前量 L，不足则提前请求或自动回退。
4. **防抖与防死锁**：dwell-time + 滞回；交接活性检查器拒绝可能无限抖动的策略。

### 2.2 IP-61 DEPENDABILITY-ENGINE（可信性引擎 DEP）
1. **可信性四元组估计**：在线估计 R_safety/R_liveness/A/M，维护 D 的置信区间。
2. **共因失效审计**：枚举 S_shared，估 β，拒绝无证据的「人机独立/冗余」声明。
3. **可靠性预算 + 退化阶梯**：ρ 记账；预算不足单调降级；上升级重新持证。
4. **可用性下限守护**：A_min 硬约束，防止「安全但不可用」被优化成最优解。

### 2.3 IP-62 HANDOFF-VALIDATOR（交接验证器 HOV）
1. **接管延迟注入**：按 persona/疲劳/分心分布注入 T_h，检验前置时间与 safe-hold。
2. **共因失效注入**：共享感知/地图/心智模型故障，检验冗余声明是否成立。
3. **交接抖动/死锁 fuzz**：高频请求、矛盾请求、快速切换，检验活性与驻留。
4. **长期可信性回归**：100h 人机协作，统计可用性、任务完成率、信任偏差。

## 4. 实验设计（E95–E102 硬门槛，承接 E87–E94）

| 实验 | 指标 | 门槛 |

## 5. 本轮最大风险

**一句话**：人机冗余很可能被共享感知/共享心智模型造成的**共因失效**同时击穿，而可靠性预算优化又会自然滑向「安全但不可用」的停机解——因此 E99（共因独立性）与 E98（可用性下限）必须设为红线，且默认回退到「单主控 + 持证 safe-hold + 保守退化」这条既 sound 又尚可用的底线。

| S_shared | 共享部件集 | 感知/地图/心智模型等共因暴露源 |
| ρ(t) | 可靠性预算 | 随运行消耗；不足则单调降级 |
| A_min | 可用性下限 | 硬约束，禁止「安全但不可用」 |
| R0≻R1≻R2≻R3≻R4 | 退化阶梯 | 共享自主→辅助→自主回退→safe-hold→MRC |
| g = τ_trust − R_sys | 信任偏差 | \|g\|≤δ_trust 为校准 |

## 2. 关键算法（伪代码）

### IP-60 SAC：交接证书编译、共形前置时间与原子转移
```
def plan_handoff(C_from, C_to, human, alpha_takeover, now):
    T_star = conformal_takeover_quantile(human.persona, alpha_takeover)  # T_h^α
    L      = T_star + EPS                                                # 前置时间
    window = [now, now + L]
    if not overlap(C_from.safe_set, C_to.safe_set, window):
        return HandoffReject(reason="safe-set gap")                      # 定义 45(1)
    if not human.ready_calibrated():                                     # 定义 45(2)
        return HandoffRequest(lead_time=L, ui=prompt(human.trust_gap))
    hold = safe_hold_cert(C_from, horizon=L)                             # 过渡期 safe-hold
    return HandoffCert(from_=C_from, to=C_to,
                       t_start=now, t_deadline=now + L,
                       hold=hold, rollback=rollback_to(C_from),
                       dwell=DELTA_DWELL)

def execute_handoff(H, authority_fsm, t):
    assert authority_fsm.safe_hold_active(H.hold)                       # 定义 45(3)
    ack = handshake(H.to, deadline=H.t_deadline)
    if ack.timeout:
        return rollback(H.rollback)                                     # 定义 45(4) 回滚
    if overlap_guaranteed(H.from_, H.to, t):
        return atomic_transfer(H.from_, H.to)                           # 单一主控原子切换
    return abort_and_hold()                                             # 绝不出现无主控窗口

def accept_handoff_request(req, recent_handoffs, now):
    # 活性/防抖：驻留不足则抑制，阻止无限抢权
    if now - recent_handoffs[-1].t < DELTA_DWELL:
        return Reject(reason="dwell")
    return admit(req)
```

### IP-61 DEP：可信性估计、共因审计、预算与退化阶梯
```
def dependability_update(blocks, events, shared_components):
    R_safety = ratio(e.safe for e in events)
    R_live   = 1.0 - deadlock_rate(events)
    A        = uptime(events) / horizon(events)
    M        = maintainability(events)
    beta     = common_cause_factor(shared_components)     # 显式列举 S_shared
    R_ind    = series_parallel(blocks)                    # 假设独立
    R_cc     = common_cause_reliability(shared_components)
    R_sys    = (1 - beta) * R_ind + beta * R_cc           # 定义 47
    return D(R_safety, R_live, A, M, R_sys=R_sys, beta=beta)

def certify_independence(shared_components, beta, beta_max):
    if shared_components and beta > beta_max:
        return IndependenceCertificate(valid=False,
               reason="shared perception ⇒ human-machine redundancy not proven")
    return IndependenceCertificate(valid=True, shared=shared_components, beta=beta)

def spend_budget(rho, rung, dt):
    cost = rung.consumption * dt
    if rho - cost < rung.floor_required:
        return descend_one(rung)                          # 定义 48：只降一级
    return rho - cost

def select_rung(rho, goal, D):
    for rung in ladder_descending():                      # R0 → R4 从最有用开始
        if (rung.feasible(goal) and rho >= rung.floor_required
                and D.meets(rung.needs) and D.A >= A_MIN):
            return rung
    return MRC_SAFE_STOP                                  # 底线，但仍受 A_min 审计

def ascend_rung(target, handoff_cert, D):
    if handoff_cert.valid and handoff_cert.to == target and D.A >= A_MIN:
        return target                                     # 上升必须重新持证
    return no_ascend(reason="recertify required")
```

### IP-62 HOV：延迟/共因/抖动注入与长期回归
```
def handoff_fuzz(scenarios, N):
    cex = []
    for s in sample(scenarios, N):
        inject_latency(s, dist=persona_takeover[s.persona])   # T_h 分布
        inject_ccf(s, shared=s.shared_components)             # 共因失效
        inject_flapping(s, rate=s.burst_rate, dwell=DELTA_DWELL)
        trace = simulate_v9(s)
        if not check_handoff(trace):                          # 无主控/回滚/重叠
            cex.append(trace); continue
        if not check_liveness(trace):                         # 死锁/抖动
            cex.append(trace); continue
        if not check_ccf_claim(trace):                        # 独立性声明被击穿
            cex.append(trace)
    return cex

def check_handoff(trace):
    return (no_unowned_window(trace) and rollback_ok(trace)
            and safe_hold_covers_transition(trace))

def check_liveness(trace):
    return not deadlock(trace) and flapping_rate(trace) < FLAP_MAX
```

## 6. 本轮最大风险

**一句话**：人机冗余很可能被共享感知/共享心智模型造成的**共因失效**同时击穿，而可靠性预算优化又会自然滑向「安全但不可用」的停机解——因此 E99（共因独立性）与 E98（可用性下限）必须设为红线，且默认回退到「单主控 + 持证 safe-hold + 保守退化」这条既 sound 又尚可用的底线。
