# 第 13 轮（新循环第 1 轮）· SKILL-FORGE：把 32 个任务重标成技能，用 LoRA 专家 + 用户共创技能卡锻造成一个单模型

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是灵感循环新循环第 1 轮，三个词是「LoRA」「技能学习」「用户共创」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是在它们之上补一层**数据与技能抽象**：先把 32 个任务压成约 10 个跨任务技能，再把每个技能写成人类可编辑、可验证、可执行的 **Skill Card**，用**一个技能条件 LoRA**吸收跨任务数据，用**确定性技能图 + CHUNK-SERVO**执行，最终仍然只交一个 checkpoint。

## 0. 先给结论：不要把 32 个任务当 32 个策略，要把它们当 10 个技能

截至 2026-10-31，官网榜单页仍是 **Coming Soon** 遮罩；`leaderboard.html` 源码注释写明榜单行是 **randomly-generated**，`runs.html` 也是 **Coming Soon**，`leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`，且出现 27.29%、27.85% 等非 10 次 trial 整数倍。**第 12 轮把 29.7% 当真实 SOTA 是错误前提，本轮必须更正：这些数字是预览占位，不是难度表，也不是可追赶的 SOTA。** 公开模型家族（MolmoAct2、WALL-OSS-0.5、DreamZero、Spirit-v1.5、DM0、π0.5、GigaBrain-0、GR00T N1.5）可以作为技术路线参考，但不能把占位分数当实测结论。

真正确定的事实是：

1. **32 个任务、每任务 10 次、每次 180 秒、单模型**。排名先看 32 任务平均成功率，再看步骤分，最后看提交时间。
2. **32 个任务共享大量原子技能**。挂杯、插充电器、插网线、装铅笔盒都包含“对准—插入—卡合”；开瓶、开锁、拉拉链、盖盒都包含“关节操作”；整理工具、水果分类、颜色排列都包含“抓取—搬运—放置—排序”。按任务训策略，每个任务只有约 1,000 条演示；按技能聚合，每个技能可覆盖 3–8 个任务。
3. **官方 WLA 支持 LoRA**：6B 模型，冻结 VLM，只训 action head/projector；官方文档给出 `--use_lora true --lora_rank 16 --lora_alpha 32`，单张 24GB GPU 可跑，能保存 adapter-only checkpoint。**这使“多技能 LoRA 专家”在工程上可行，但最终必须合并/蒸馏成一个适配器，不能运行时按任务切换。**
4. **任务信息端点暴露了评分步骤和泛化注释**。`tasks_v2/<slug>/info.json` 给出 `score_steps`（每步多少分）和 `generalization`（未见物体、人为干扰的具体说明）。这正好是技能级弱标签和技能级评测的原料。
5. **数据量足够做技能重标**：32 个数据集合计 33,276 episodes / 18,282,246 frames / 169.28 h / 30 fps；HangCup 单任务 1,043 episodes。技能片段不是从零采集，而是从现有成功演示里重新切分。

所以本轮的押注是 **SKILL-FORGE**：

> 用 `scoring_points + 夹爪事件 + EE 轨迹变点 + 视觉接触代理` 把 32 个任务重标成约 10 个跨任务技能；用人类共创的 **Skill Card** 把技能定义、锚点、成功谓词、恢复动作和泛化压力场景写成可执行契约；用**一个技能条件 LoRA（SC-LoRA）**吸收跨任务片段；用**确定性技能图 + CHUNK-SERVO**在线调度；最终只交一个 checkpoint。

一句话：**把“任务级监督”换成“技能级契约”，把“每任务一个模型”换成“每技能一份数据 + 一个技能条件适配器”。**

三个灵感词怎么落地：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **LoRA** | 冻结 WLA VLM，在 action expert 上注入一个技能条件 LoRA；技能专家只做离线初始化/消融，最终合并或蒸馏成一个 adapter | 不做 32 个任务各一个 LoRA；不在运行时按任务切换 adapter；不把 LoRA 当第二个模型 |
| **技能学习** | 32 任务 → 10 技能；跨任务片段池化；技能图调度；技能级成功谓词和恢复 | 不做纯任务标签分类；不假设技能分割一定正确；不把技能当自由文本 prompt |
| **用户共创** | Skill Card 注册表：工程师写契约、标注员验片段、任务 owner 写成功谓词、社区提交失败片段/压力场景/语言变体 | 不让用户上传可执行代码；不让未审核卡片进训练；不依赖外部数据绕过规则 |

### 1.3 数据、相机与动作空间

- 数据规模：32 个数据集合计 **33,276 episodes / 18,282,246 frames / 169.28 h / 30 fps**；HangCup 单任务 **1,043 episodes / 194,564 frames**。平均每任务约 1,040 条演示，按任务微调很容易过拟合。
- 相机：头双目已校正，基线 **58.2526 mm**，`fx≈282.37`；**腕部相机并非没有内参**——`camera_params.wrist_left.color.camera_matrix` 存在，`fx≈436.4`、`fy≈435.9`，`cx≈323.9`、`cy≈242.9`，并有畸变参数。第 12 轮“腕部无内参”的说法必须修正。
- 观测：四路 RGB 480×640；没有 depth、camera_info、force/torque、tactile。动作：双臂关节 `[7]`、EE 位姿 `[6]`、夹爪 `[1]`、下身体 `[15]`，`joint` 与 `ee` 互斥；`action.pivot` 字段存在，可用于相对动作。
- 评测：单次 180 秒；`action_chunk_size` 固定；chunk 内无新观测；每次 `get_action` 必须带 `meta.token`；评测端记录延迟/波动/动作统计。

### 1.4 WLA 与 LoRA 的工程边界

官方 UnifoLM-WLA-1.0：**6B**，约 2,500 h 真机数据，64 任务；统一 **54D action / 60D state**；默认 `chunk_size=30`、`target_fps=30`、4 步扩散去噪；微调冻结 VLM，只训 DiT action head + robot-state projector，单张 **24GB** GPU 可跑；支持 `--use_lora true --lora_rank 16 --lora_alpha 32 --lora_target_modules ...`，可保存 adapter-only checkpoint。来源：`https://github.com/unitreerobotics/unifolm-wla`、`https://github.com/unitreerobotics/unifolm-wla/blob/main/docs/train_action_expert_en.md`（检索于 2026-10-31）。

**工程含义**：可以并行训练多个技能 LoRA 专家做实验；但提交时只能加载一个合并/蒸馏后的 adapter。不要把“多 LoRA”误做成“多模型”。

## 2. 诊断：瓶颈是“任务级监督”，不是模型容量

### 2.1 三个错配

1. **数据错配**：32 个任务各有约 1,000 条演示，但“抓取”“插入”“放置”这些技能在任务间重复。按任务训练，每个任务只看到自己的 1,000 条；按技能聚合，同一个技能能看到 3–8 个任务的数千条片段。任务标签把可复用的数据切碎了。
2. **评测错配**：官方按任务成功率排名，但失败往往发生在技能层：没抓住、没对准、没插进去、没保持住、没恢复。只报任务成功率，无法知道是“语义选错”还是“最后 3 厘米没对准”，也就无法把工程投到正确位置。
3. **模型错配**：单模型规则禁止“每个任务一个策略”；但 LoRA 又允许低成本 specialization。正确做法不是“每任务一个 LoRA”，而是“每技能一份数据 + 一个技能条件适配器”，把 specialization 收进一个 checkpoint。

### 2.2 为什么是现在

- WLA 的 LoRA 微调在 24GB 上可跑，技能专家实验成本从“训 32 个 6B 模型”降到“训 10 个小 adapter”。
- `tasks_v2` 暴露 `score_steps` 和 `generalization`，第一次有足够的弱标签做技能级重标和技能级压力测试。
- 33k 条演示已经覆盖了主要技能，不需要从零采集；需要的是重新组织，而不是更多数据。
- 榜单是占位，说明现在没有可靠的公开 SOTA 可追；此时建立内部技能级评测的收益，高于追逐一个会变的预览数字。
- 第 12 轮已经把控制层做到“5 步伺服”；本轮把“技能选择/技能数据/技能评测”补上，形成完整闭环。

### 2.3 四个可证伪假设

| 假设 | 预测 | 检验 |
|---|---|---|
| H1 跨任务技能池化有效 | 同一技能在 held-out 任务上优于单任务 LoRA | G2/G3 |
| H2 一个技能条件 LoRA 优于一个普通多任务 LoRA | 技能条件化带来 +2–5pp，且不增加推理模型数 | G2/G4 |
| H3 Skill Card 不只是 prompt | 卡片驱动的分割/恢复/评测优于“只把技能名拼进语言指令” | G1/G3/G5 |
| H4 技能图 + CHUNK-SERVO 对接触密集任务有效 | S5/S6 任务的步骤分和成功率提升，非接触任务不退化 | G3/G5 |

## 3. 方法：SKILL-FORGE

### 3.1 技能分类：10 个跨任务技能

技能不是任务标签，而是“可复用的感知—动作—验证单元”。本轮用 10 个技能覆盖 32 个任务；双臂协调作为横切模式，不单列，避免技能碎片化。

| 技能 | 定义 | 主要覆盖任务 | 关键成功信号 | 典型恢复 |
|---|---|---|---|---|
| S1 接近/对准 | 把夹爪移到目标可抓/可插的预位姿 | 全部任务（横切） | 目标在腕部视野中心、距离进入阈值 | 后退 2cm、重新居中 |
| S2 抓取/夹持 | 闭合夹爪并建立稳定夹持 | 全部操作任务（横切） | 夹爪闭合、物体随动、无滑移 | 重新张开、换抓点 |
| S3 提起/搬运 | 在保持夹持的同时移动到目标区域 | T01–T04、T06–T10、T13、T15、T17–T21、T23–T29、T31–T32 | 物体离台、轨迹无碰撞 | 降低速度、抬高 1cm |
| S4 放置/堆叠/对位 | 把物体放到支撑面/容器/堆叠位 | T01–T04、T06–T10、T13、T15、T17–T21、T23–T29、T31 | 支撑/包容/堆叠稳定 | 重新对位、轻放 |
| S5 插入/悬挂/装配 | 沿约束轴插入、挂入、卡合 | T01、T10、T13、T26、T31 | 插入深度/卡合/悬挂稳定 | 轴向微调、旋转搜索 |
| S6 关节操作 | 开合、旋转、拉拉链、开锁、盖盒 | T03、T10、T12、T14、T18、T19、T28、T29、T32 | 关节角/盖子状态/拉链位置 | 反向微动、换接触点 |
| S7 拉拔/抽取 | 沿退出方向拔出/抽出 | T05、T11、T30 | 分离/抽出/线缆脱落 | 小幅摆动、换夹点 |
| S8 倾倒/转移 | 控制容器姿态把内容物转移 | T14、T32 | 内容物进入目标、无洒出 | 降低倾角、靠近 |
| S9 变形物/柔性物 | 折叠、塞入、压合、整理布料/袋子 | T03、T16、T18、T19 | 折叠边/塞入深度/袋子闭合 | 重新展平、换抓边 |
| S10 分类/排序/多物体序列 | 按类别/颜色/顺序重复抓放 | T02、T04、T06、T09、T15、T17、T21、T22、T24 | 顺序正确、类别正确、全部完成 | 重新识别、回到上一个物体 |

完整的 32 任务 × 技能矩阵见产物区。这里先说明设计原则：**一个任务可以触发多个技能，一个技能也可以跨多个任务；技能边界由“可验证的状态变化”定义，而不是由任务名定义。**

### 3.2 Skill Card：把技能写成可执行契约

Skill Card 不是 prompt 模板，而是四层共用的契约：

1. **数据层**：告诉重标器哪些片段属于该技能、哪些帧是边界、哪些片段是高置信。
2. **训练层**：告诉 LoRA 训练器技能 ID、技能 embedding、采样权重、辅助损失。
3. **控制层**：告诉在线调度器前置条件、后置条件、成功谓词、恢复动作、chunk 长度、伺服增益。
4. **评测层**：告诉评测器该技能的成功标准、失败模式、泛化压力场景。

最小 schema：

```yaml
skill_id: S5.insert_hang
version: 1.0.0
name: 插入/悬挂/装配
definition: "将受器对准目标轴/钩/槽，沿约束方向推进，直到卡合、悬挂或支撑稳定"
applies_to: [T01, T10, T13, T26, T31]
preconditions:
```

卡片必须能通过**静态校验**（字段、单位、范围、引用存在）、**回放校验**（在 held-out 演示上谓词可触发、恢复不冲突）、**覆盖率校验**（每个技能至少覆盖 2 个任务，每个任务至少归属 1 个技能）和**安全校验**（工作空间、速度、夹持力上限）。未通过的卡片只能停在 `draft`，不能进训练。

### 3.3 跨任务重标：从 32 个任务到技能片段

重标不是人工看 33k 条视频，而是“弱标签 + 变点检测 + 少量人工抽检”：

1. **步骤数弱标签**：`score_steps` 给出每个任务有几步。例如 HangCup 2 步、FoldTowel 5 步、ToolboxStorage 4 步。步数不是技能数，但给出了每集应有的边界数量。
2. **夹爪事件**：夹爪开/合/保持是抓取、释放、插入前后的强信号。
3. **EE 轨迹变点**：末端速度/加速度的突变、长时间停留、方向反转，通常是“接近→抓取”“搬运→放置”“插入→卡合”的边界。
4. **视觉接触代理**：腕部图像中夹爪与物体的重叠、光流突变、物体遮挡变化；没有力/触觉，只能用视觉代理，不能声称真接触。
5. **语言/任务先验**：任务名和 `score_steps` 文本映射到技能候选集，作为分割的先验，不作为硬标签。

对每集做带约束的动态规划：在 `K` 个评分步骤对应的 `K` 个片段上，最大化变点分数、最小化片段长度方差、惩罚与先验技能不符的分配。输出 `(episode, start, end, skill_id, confidence)`。置信度低的片段不进入训练，只进入人工抽检队列。人工只需每任务抽 2–3 集确认边界和技能标签；目标不是“全标注”，而是“够用的高置信种子”。

### 3.4 SC-LoRA：一个技能条件适配器

**架构**：WLA backbone 冻结 VLM；在 action expert 的线性层注入 LoRA `W = W_0 + B A`；技能条件通过一个小的 skill embedding `z_s` 注入 action expert（FiLM/AdaLN 或 prefix token）。`z_s` 来自 Skill Card 的可学习 embedding + 卡片结构编码，推理时由语言指令检索卡片得到，不需要任务 ID。

**损失**：

```text
L = L_flow + λ1 * L_skill + λ2 * L_boundary + λ3 * L_card
```

- `L_flow`：WLA 原有的 flow-matching 动作损失。
- `L_skill`：用动作 expert 的池化特征预测技能 ID，防止技能条件退化成无用 embedding。
- `L_boundary`：技能切换处的动作平滑/一致性，减少“切技能时抖一下”。
- `L_card`：可选的阶段进度监督，用卡片的前置/后置条件构造弱标签。

**训练**：技能平衡采样 `p(s) ∝ n_s^(-0.5)`，避免 S4 这种大技能淹没 S5/S7；LoRA rank 16、alpha 32、lr 1e-4、batch 32、20k steps；单卡 24GB 可跑。最终只保存一个 adapter。

**为什么不是每任务 LoRA**：每任务 LoRA 在 1,000 条演示上容易过拟合，且推理时要切换 32 个 adapter，违反单模型精神。每技能 LoRA 专家可以作为离线初始化：先训 `ΔW_s`，再用 TIES/GRAM/LoRA soup 合并，或蒸馏回 SC-LoRA；但**主方案是直接训练一个 SC-LoRA**，合并只作为消融和 fallback。

### 3.5 在线：确定性技能图 + CHUNK-SERVO

在线不加载第二个学习模型，只加载一个 SC-LoRA checkpoint + 一个卡片注册表 + 一个确定性调度器。

```text
observe o_t, state s_t, instruction l
card = retrieve_card(l, o_t)          # 语言/场景检索，不是学习模型
skill = card.skill_id
while not done:
    z = card.embedding
    chunk = policy(o_t, s_t, l, z)     # SC-LoRA，一次前向
    for a in chunk[:card.chunk_horizon]:
        execute(a)
        if card.terminate(o_t): break
        if card.failure(o_t): break
    if card.success(o_t):
        skill = graph.next(skill)      # 确定性转移
    elif card.failure(o_t):
        skill = card.recovery_skill    # 卡片指定恢复
```

- **技能图**：`S1 → S2 → S3 → S4/S5 → verify`；`S6`、`S8`、`S9` 作为子图插入；`S10` 是“对每个物体循环 S1–S4”的宏技能。转移条件是卡片谓词，不是学习出来的。
- **CHUNK-SERVO**：保留第 12 轮的“30 步规划 + 5 步视觉伺服”；但每个技能可以用自己的 `chunk_horizon`（3–15）、伺服增益、终止谓词。接触段（S5/S6）用更短 chunk 和更低增益；自由空间搬运（S3）用更长 chunk。
- **合规**：调度器是配置/控制器，不是第二个学习模型；最终提交只有一个 checkpoint、一个 adapter；没有按任务加载不同权重。

### 3.6 用户共创：Skill Card 注册表

用户共创不是“让用户发 prompt”，而是让用户贡献**结构化、可验证、可拒绝**的卡片和压力场景：

| 贡献类型 | 谁来做 | 产物 | 验证 |
|---|---|---|---|
| 技能定义/锚点 | 机器人工程师 | YAML 卡片 | schema + 回放 |
| 片段标注 | 标注员/任务 owner | `(episode, start, end, skill)` | 置信度 + 双人复核 |
| 成功谓词 | 任务 owner | `success_predicates` | held-out 回放 |
| 失败片段 | 参赛社区 | 短视频 + 失败技能标签 | 归因 + 去重 |
| 泛化压力场景 | 社区/评测者 | 位置/遮挡/背景/人为扰动配置 | 可复现 + 安全 |
| 语言变体 | 社区 | 中英文指令 | 覆盖 + 不歧义 |

流水线：`提交 → 静态校验 → 回放校验 → 双人评审 → 注册表 → 训练/评测`。所有卡片带版本号、作者、许可证、变更记录；用户不能上传可执行代码，只能提交声明式 YAML/JSON 和视频片段。未审核卡片不能进训练；训练数据仍以官方 33k 演示为主，社区贡献只做**重标、失败挖掘、压力测试**，避免规则风险。

### 3.7 失败库补丁（可选，不改变主方案）

用不计分单任务通道收集失败片段，按 Skill Card 归因到技能（没抓住/没对准/没插进/没保持/没恢复），把高置信失败片段作为 hard negatives 加入该技能的 LoRA 训练；训练后合并/蒸馏回 SC-LoRA，再跑回归。它是一条“评测→诊断→补丁→合并→复测”的闭环，不是运行时切换模型。

## 4. 竞赛策略：按技能和泛化轴投资，不按 32 个任务平均用力

- **分数数学**：每任务 100 分，32 任务总均分 `S = (1/32) Σ s_i`；排名先看平均成功率，再看步骤分。320 trials 下，`p≈0.5` 时成功率标准误约 **2.8pp**，`p≈0.25` 时约 **2.4pp**；任何小于 3pp 的差异必须用配对设计 + bootstrap 置信区间，不能单看均值。
- **投资公式**：`priority_s = f_s × r_s × h_s / c_s`。`f_s` 是技能覆盖任务比例，`r_s` 是泛化轴失败风险，`h_s` 是当前技能成功率的天花板（1 - 当前成功率），`c_s` 是工程成本。
- **优先级判断**：S4 放置覆盖最多任务，先做稳；S5 插入/悬挂和 S6 关节操作覆盖 T01/T10/T12/T13/T14/T19/T26/T28/T29/T31，是“最后 3 厘米”和“接触密集”的主要来源，优先做技能卡 + CHUNK-SERVO；S7 拉拔只覆盖 3 个任务，但成本低，可作为快速收益；S9 变形物难度高、泛化轴窄，放在第二梯队。
- **单任务不计分通道**：每个技能选 2–3 个代表任务，做配对 A/B（同初始状态、同语言、同 trial 数）。它不计分，但能在不消耗正式 320 trials 的情况下筛掉坏想法。
- **提交组合**：先交“官方 WLA 微调 + 安全动作限制”的基线锁 tie-break；再交“SC-LoRA + CHUNK-SERVO”；最后交“卡片恢复 + 失败库补丁”。每次提交只改一个变量，保留回滚。
- **不要做**：不追占位榜单排名；不把 32 个任务各训一个策略；不在评测时按任务切换 adapter；不把社区压力场景直接当训练数据。

## 7. 风险与合规

| 风险 | 概率/影响 | 缓解 | 触发回退 |
|---|---|---|---|
| 技能分类过粗/过细 | 中/高 | 用 G1 做粒度消融；以“可验证状态变化”为准 | 回退到任务级技能 |
| 分割噪声大 | 高/中 | 多信号 + 置信度阈值 + 每任务 2–3 集人工抽检 | 只用高置信片段 |
| LoRA 负迁移/合并冲突 | 中/高 | 技能平衡采样；TIES/GRAM 合并；held-out 验证 | 回退单多任务 LoRA |
| 单模型规则 | 低/高 | 最终一个 checkpoint、一个 adapter；调度器确定性 | 删除多 adapter 方案 |
| 社区内容质量/安全 | 中/中 | 声明式 YAML、沙箱回放、双人评审、许可证检查 | 只用官方数据 |
| 320 trials 方差 | 高/中 | 配对 A/B、bootstrap、单任务通道多测 | 不宣称 <3pp 的结论 |
| 延迟超标 | 中/高 | 一次前向、预计算卡片 embedding、技能级 chunk | 降 rank/缩短 chunk |
| 规则不明确 | 中/高 | 先按保守解释；向主办方确认外部数据/社区贡献 | 只交官方数据训练的单模型 |

**合规底线**：最终提交只有一个学习模型/一个 checkpoint；Skill Card 和技能图是配置/控制器，不是第二个模型；LoRA 专家只做离线训练脚手架；不按任务加载不同 adapter；社区贡献只做重标/失败挖掘/压力测试，不直接引入外部训练数据；所有动作受工作空间、速度、夹持力安全限制。

# 第 13 轮产物 · SKILL-FORGE 技术报告：技能卡、跨任务重标、单适配器与技能级评测

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「SKILL-FORGE」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是在它们之上补“技能数据契约 + 单适配器技能条件化 + 技能级评测”。

## 0. 结论与边界

**结论**：在 32 任务、每任务约 1,000 条演示、单模型、无 depth/force/tactile 的约束下，最值得做的不是再堆一个更大的 VLA，而是把任务级数据重新组织成技能级数据，并把技能写成人类可编辑、机器可验证的 **Skill Card**。具体路线：

1. 用 `score_steps + 夹爪事件 + EE 轨迹变点 + 视觉接触代理` 把 32 个任务重标成约 10 个跨任务技能；
2. 用 **Skill Card** 把技能定义、锚点、成功谓词、恢复动作、泛化压力场景写成声明式契约；
3. 用**一个技能条件 LoRA（SC-LoRA）**在官方 WLA 上吸收跨任务片段；
4. 用**确定性技能图 + CHUNK-SERVO**在线执行；
5. 最终只交一个 checkpoint、一个 adapter，技能图是控制器/配置，不是第二个学习模型。

**边界**：

### 1.4 WLA 与 LoRA 的工程边界

官方 UnifoLM-WLA-1.0：

- 6B；约 2,500 h 真机数据；64 任务；统一 54D action / 60D state。

- 支持 LoRA：`--use_lora true --lora_rank 16 --lora_alpha 32 --lora_target_modules ...`；可保存 adapter-only checkpoint。
- 来源：<https://github.com/unitreerobotics/unifolm-wla>、<https://github.com/unitreerobotics/unifolm-wla/blob/main/docs/train_action_expert_en.md>（检索于 2026-10-31）。

**工程结论**：可以并行训练约 10 个技能 LoRA 专家做实验；但最终必须合并或蒸馏成一个 adapter，不能运行时按任务切换。

## 2. 问题形式化

### 2.1 任务、回合、技能

设任务集合 `T = {T_1, ..., T_32}`，任务 `T_i` 有语言指令 `l_i`，评测 trial `ξ_{ij}`（`j=1..10`）产生观测序列：

```text
τ_{ij} = {(o_t, s_t, a_t)}_{t=0}^{L_{ij}-1}
```

其中 `o_t` 是四路 RGB，`s_t` 是 60D 机器人状态（含双臂、夹爪、下身体），`a_t` 是 54D 动作。任务成功/步骤分由官方评测器给出：

```text
R_i(π) = (1/10) Σ_{j=1}^{10} r_i(π; ξ_{ij}),  r_i ∈ [0, 100]
S(π) = (1/32) Σ_{i=1}^{32} R_i(π)
```

设技能集合 `S = {S_1, ..., S_K}`，`K=10`。每个时刻有一个技能标签 `z_t ∈ S`，并把回合切成 `M` 个连续片段：

```text
0 = b_0 < b_1 < ... < b_M = L,   z_t = S_{m} for t ∈ [b_{m-1}, b_m)
```

技能不是任务标签；一个任务可以包含多个技能，一个技能可以跨多个任务。技能由“可验证的状态变化”定义，例如 S5 插入/悬挂的成功是 `insertion_depth >= d_min` 或 `hang_support == stable`，不是“任务名包含 plug”。

### 2.2 Skill Card 作为契约

每张卡片：

```text
C_s = (id_s, pre_s, post_s, anchor_s, lang_s, succ_s, fail_s, rec_s, gen_s, ctrl_s, prov_s)
```

其中：

- `pre_s` / `post_s`：前置/后置条件；
- `anchor_s`：抓取点、放置点、插入轴、支撑面、间隙；
- `lang_s`：中英文语言变体；
- `succ_s` / `fail_s`：成功/失败谓词；
- `rec_s`：恢复技能序列；
- `gen_s`：位置/干扰物/背景/未见物体/人为扰动的压力配置；
- `ctrl_s`：chunk 长度、伺服增益、最大重试；
- `prov_s`：作者、评审、许可证、版本、来源片段。

卡片编译器把 `C_s` 编译成四件东西：

```text
C_s  ->  (e_s, w_s, δ_s, E_s)
```

- `e_s`：技能 embedding（训练/推理用）；
- `w_s`：采样权重（训练用）；
- `δ_s`：调度器配置（在线用）；
- `E_s`：技能评测套件（评测用）。

### 2.3 单模型约束的形式化

保守解释：最终策略必须是一个 checkpoint，不允许按任务 ID 选择不同权重。形式化：

```text
π_θ(a | o, l) = π_{θ_0 + ΔW}(a | o, l, R(l, o))
```

其中：

- `θ_0` 是 WLA 基座；
- `ΔW` 是**唯一**的 LoRA adapter；
- `R(l, o)` 是确定性的卡片检索器，输出技能 ID/embedding；
- 不存在 `ΔW_i` 按任务 `i` 切换。

技能图/调度器 `δ` 是控制器，不是学习模型；它的参数是卡片里的阈值/谓词，不是训练出来的权重。这样既保留技能 specialization，又满足单模型约束。

### 2.4 目标函数

技能级训练目标：

```text
max_θ  Σ_s w_s * E_{(o,l,a) ~ D_s} [ log π_θ(a | o, l, e_s) ]
       - λ_skill * L_skill - λ_boundary * L_boundary
```

其中 `D_s` 是重标后的技能片段池，`w_s` 是技能平衡权重。评测目标：

```text
max_θ  S(π_θ) = (1/32) Σ_i R_i(π_θ)
s.t.   一个 checkpoint；p95 延迟 ≤ B；动作/工作空间安全约束
```

训练目标与评测目标之间的桥是“技能级指标”：如果技能级成功率和步骤分提升，且技能覆盖任务不退化，才允许进入正式评测。

技能图的转移条件来自卡片：

- `S2 -> S3`：`grasp_stable == true`；

- `S3 -> S5`：`axis_aligned == true`；

## 4. Skill Card 规范

### 4.1 设计原则

1. **声明式**：只允许 YAML/JSON 字段，不允许用户上传可执行代码。
2. **可验证**：每个谓词必须能在 held-out 片段上回放；每个阈值有单位/范围。
3. **可版本化**：语义化版本；每次修改带 diff、作者、评审、变更原因。
4. **可组合**：技能卡可以引用其他卡片（如 S5 引用 S2 的抓取谓词）。
5. **可拒绝**：未通过静态/回放/安全校验的卡片不能进训练。

### 4.2 字段规范

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `skill_id` | string | 是 | `S5.insert_hang`，全局唯一 |
| `version` | semver | 是 | 卡片版本 |
| `name` | string | 是 | 中文/英文名 |
| `definition` | string | 是 | 一句话定义，必须包含可观察状态变化 |
| `applies_to` | list[task_id] | 是 | 适用任务，允许 `*` 但需理由 |
| `preconditions` | list[predicate] | 是 | 前置条件 |
| `postconditions` | list[predicate] | 是 | 后置条件 |
| `anchors` | map | 是 | 抓取点/放置点/插入轴/支撑面/间隙 |
| `language_variants` | map[lang, list] | 是 | 中英文指令变体 |

| `recovery` | list[skill_id/action] | 是 | 恢复序列 |
| `generalization_knobs` | map | 是 | 五类泛化压力参数 |
| `control` | map | 是 | chunk/增益/重试/安全上限 |
| `provenance` | map | 是 | 作者/评审/来源/许可证 |
| `status` | enum | 是 | draft/replay/review/approved/deprecated |

### 4.4 校验规则

1. **静态校验**：字段齐全；`skill_id` 唯一；单位/范围合法；`applies_to` 存在；`recovery` 引用存在；许可证允许。
2. **回放校验**：在 held-out 片段上，`preconditions` 在片段开始处为真、`postconditions` 在结束处为真；谓词触发率在合理区间；恢复动作不产生循环。
3. **覆盖率校验**：每个技能至少覆盖 2 个任务；每个任务至少归属 1 个技能；每个任务至少有一个可执行的 `success_predicates`。
4. **冲突校验**：同一任务的两张卡片不能给出互斥的 postcondition；技能图不能有不可达节点；恢复图不能有无限循环。
5. **安全校验**：工作空间、速度、夹持力、最大重试、abort 条件；涉及人形干扰的卡片必须有“停止/后退”优先策略。

校验不通过 -> `draft`；通过 -> `replay`；双人评审 -> `approved`；线上评测退化 -> `deprecated`。

### 4.5 卡片编译器

```text
compile(C_s):
  e_s = Embedding(skill_id) + MLP(structural_features(C_s))
  w_s = 1 / (n_s + eps)^alpha
  delta_s = {
    chunk_horizon: C_s.control.chunk_horizon,
    servo_gain: C_s.control.servo_gain,
    max_retries: C_s.control.max_retries,
    success: C_s.success_predicates,
    failure: C_s.failure_modes,
    recovery: C_s.recovery
  }
  E_s = build_eval_suite(C_s.generalization_knobs, C_s.applies_to)
  return (e_s, w_s, delta_s, E_s)
```

`e_s` 进 SC-LoRA；`w_s` 进采样器；`delta_s` 进在线调度器；`E_s` 进技能级评测。四层共用一张卡，避免“训练一套、评测另一套”。

## 5. 跨任务重标

### 5.1 信号

| 信号 | 计算 | 用途 | 局限 |
|---|---|---|---|
| 评分步骤数 | `K = len(score_steps)` | 每集边界数先验 | 步骤不等于技能 |
| 夹爪开合 | `g_t ∈ {0,1}`；`Δg_t` | 抓取/释放边界 | 插入/旋转不改变夹爪 |
| EE 速度/加速度 | `v_t = p_t - p_{t-1}`；`a_t = v_t - v_{t-1}` | 接近/搬运/放置边界 | 平滑轨迹变点弱 |
| 停留/方向反转 | `norm(v_t) < ε` 持续；`v_t · v_{t+1} < 0` | 对准/插入/失败重试 | 可能误切 |
| 视觉变化 | 帧差/光流/CLIP 特征差 | 物体移动/遮挡/场景切换 | 相机自运动干扰 |
| 接触代理 | 夹爪-物体重叠、物体随动、光流突变 | 抓取/插入/接触段 | 没有力/触觉，不是真接触 |
| 文本先验 | `score_steps` 关键词 → 技能候选 | 弱标签 | 文本与视觉不对齐 |

### 5.2 分割算法

输入：一集 `τ`，评分步骤数 `K`，特征 `c_t`（归一化后的变点分数），最小/最大片段长度 `L_min/L_max`。

目标：找 `K` 个片段 `b_0=0 < ... < b_K=L`，最大化：

```text
F(b) = Σ_{m=1}^{K} Σ_{t=b_{m-1}+1}^{b_m} c_t
       - λ_1 Σ_{m=1}^{K} |(b_m - b_{m-1}) - L/K|^2
       - λ_2 Σ_{m=1}^{K} 1[skill_prior(b_{m-1}, b_m) == invalid]
```

动态规划：

```text
DP[m][t] = max_{t' < t, L_min <= t-t' <= L_max}
             DP[m-1][t'] + C(t', t) - λ_1 * (t-t' - L/K)^2
```

其中 `C(t',t) = Σ_{u=t'+1}^{t} c_u`。回溯得到边界。

### 5.3 技能分配与置信度

每个片段根据 `score_steps` 文本、任务先验、视觉状态分配技能。允许多对一/一对多：

- 一个评分步骤可以包含多个技能（如“抓住并挂上” = S2 + S3 + S5）；
- 一个技能可以跨多个评分步骤（如“整理 4 个工具” = S10 循环 S2/S4）。

置信度：

```text
conf = (F_best - F_second) / (|F_best| + eps)
       * agreement_with_prior
       * human_review_score
```

只有 `conf >= τ_conf` 的片段进入训练；低置信片段进入人工队列。人工每任务抽 2–3 集，标边界和技能；目标 κ≥0.7。

### 5.4 数据统计与采样

预期分布（需 G1 实测）：

- S4 放置/堆叠：覆盖任务最多，片段数最多；
- S2 抓取：几乎每个任务都有，但片段短；
- S5 插入/S6 关节：片段少、难度高，必须过采样；
- S7 拉拔：只覆盖 3 个任务，片段最少；
- S9 变形物：片段长、边界模糊，需要更高人工抽检率。

采样器：

```text
p(s) ∝ n_s^(-α),  α=0.5
```

再加任务平衡：每个 batch 至少包含 2 个不同任务的片段，避免技能条件记住任务 ID。

### 5.5 质量门

- 边界 F1 ≥0.75；
- 技能分类准确率 ≥0.85；
- 置信度校准误差（ECE）≤0.1；
- 人工复核 κ≥0.7；
- 每个技能至少 500 个高置信片段（不足则降低该技能的训练权重）。

## 6. SC-LoRA：单适配器技能条件化

### 6.1 架构

```text
o_t, s_t, l
   |
   +--> WLA VLM (frozen) --> visual/state tokens
   |
   +--> Card Retriever R(l,o) --> skill_id s --> e_s
   |
   +--> Action Expert (DiT) with LoRA ΔW and FiLM(e_s)
          |
          +--> action chunk a_{t:t+H}
```

LoRA：

```text
W = W_0 + B A,  B ∈ R^{d×r}, A ∈ R^{r×k}, r=16
```

技能条件（FiLM 示例）：

```text
h' = (1 + γ(e_s)) ⊙ h + β(e_s)
```

其中 `γ, β` 是小 MLP；`e_s` 来自卡片 embedding。也可以把 `e_s` 作为 prefix token 拼到 action expert 的 token 序列；FiLM 更轻，prefix 更表达，二选一做消融。

### 6.2 损失

```text
L = L_flow + λ1 L_skill + λ2 L_boundary + λ3 L_card
```

- `L_flow`：WLA 原有 flow matching：
  ```text
  L_flow = E_{t,x0,x1} || v_θ(x_t, t | o, s, l, e_s) - (x1 - x0) ||^2
  ```
- `L_skill`：技能分类辅助：
  ```text
  L_skill = -Σ_s y_s log softmax(W_c h_pool)
  ```
- `L_boundary`：技能切换处动作平滑：
  ```text
  L_boundary = Σ_{t ∈ B} || a_t - a_{t-1} ||^2
  ```
- `L_card`：阶段进度/谓词弱监督（可选）：
  ```text
  L_card = BCE(progress_head(h_pool), card_phase_label)
  ```

建议 `λ1=0.1`、`λ2=0.01`、`λ3=0.05`；以验证集扫描。

### 6.3 训练配方

| 项 | 值 | 说明 |
|---|---|---|
| 基座 | UnifoLM-WLA-1.0 | 6B |
| 冻结 | VLM | 官方微调配方 |
| 可训 | LoRA + action head + projector + skill embedding | 24GB 可行 |
| LoRA rank | 16（消融 8/32） | 官方示例 |
| LoRA alpha | 32 | 官方示例 |
| 目标模块 | action expert 线性层 | 按官方 `--lora_target_modules` |
| batch | 32（梯度累积可调） | 按显存 |
| lr | 1e-4（LoRA），1e-5（head） | 预热 5% |
| steps | 20k | 早停 |
| dtype | bf16 | 24GB |
| 数据 | 高置信技能片段 | 任务/技能双平衡 |
| 输出 | 一个 adapter | 无运行时切换 |

### 6.4 技能专家：只做离线初始化/消融

可选两阶段：

1. 对每个技能 `s`，在 `D_s` 上训练 `ΔW_s`（同 rank）；
2. 合并/蒸馏成一个 `ΔW`：
   - **TIES**：trim 小参数、elect 符号、按权重 merge；
   - **GRAM**：按组 rank-aware 合并；
   - **LoRA soup**：加权平均；
   - **蒸馏**：用 `ΔW_s` 作为 teacher，在全部 `D` 上蒸馏到 `ΔW`。

合并公式（TIES 简化）：

```text
ΔW_merged = Σ_s γ_s * TIES(ΔW_s)
```

`γ_s` 由技能验证集性能/样本量决定。合并后必须在 held-out 任务上回归；如果比直接 SC-LoRA 差，放弃合并，保留直接 SC-LoRA。

### 6.5 消融矩阵

| 方案 | 技能条件 | 适配器 | 运行时切换 | 用途 |
|---|---|---|---|---|
| B0 | 无 | 任务 LoRA | 是 | 上限参考，不合规 |
| B1 | 无 | 单个多任务 LoRA | 否 | 主 baseline |
| B2 | 任务 ID | 单个 LoRA | 否 | 排除“只是任务 ID” |
| B3 | 技能 ID | 单个 LoRA | 否 | SC-LoRA |
| B4 | 技能 ID + 卡片结构 | 单个 LoRA | 否 | 完整 SKILL-FORGE |
| B5 | 技能专家 | 多个 LoRA + oracle 路由 | 是 | 诊断上限，不合规 |
| B6 | 技能专家 | 合并成一个 LoRA | 否 | 合并消融 |
| B7 | 技能 ID + 卡片 | 单个 LoRA + CHUNK-SERVO | 否 | 最终候选 |

关键对照：B1 vs B4 证明“技能条件化”有效；B2 vs B4 证明“不是任务 ID 泄漏”；B5 vs B6 证明“合并损失可接受”；B6 vs B7 证明“控制层增值”。

## 7. 在线调度与 CHUNK-SERVO

### 7.1 状态机

```text
IDLE -> APPROACH -> GRASP -> LIFT -> TRANSFER -> PLACE/INSERT/ARTICULATE -> VERIFY
         ^            |        |          |              |
         |            v        v          v              v
         +---------- RECOVER <- FAIL <- FAIL <- FAIL <----+
```

每个状态对应一个技能卡；转移由谓词触发，不由学习模型触发。

### 7.2 伪代码

```python
def act(obs, state, instruction):
    card = retrieve_card(instruction, obs)       # deterministic
    skill = card.skill_id
    retries = 0
    while not card.success(obs):
        z = card.embedding
        chunk = policy(obs, state, instruction, z)
        for a in chunk[:card.chunk_horizon]:
            yield a
            obs, state = env.step(a)
            if card.terminate(obs):
                break
            if card.failure(obs):
                break
        if card.success(obs):
            skill = graph.next(skill)
            card = registry[skill]
            retries = 0
        elif card.failure(obs):
            retries += 1
            if retries > card.max_retries:
                skill = graph.fallback(skill)
                card = registry[skill]
                retries = 0
            else:
                skill = card.recovery_skill
                card = registry[skill]
    return
```

注意：`policy` 只加载一次；`card` 是配置；`graph` 是确定性转移表。没有第二个学习模型。

### 7.3 技能级 chunk/伺服

| 技能 | chunk horizon | 伺服增益 | 终止/恢复 |
|---|---|---|---|
| S1 接近 | 5–8 | 0.8 | 目标居中/距离阈值 |
| S2 抓取 | 3–5 | 0.4 | 夹爪闭合/物体随动 |
| S3 搬运 | 10–15 | 0.7 | 到达目标区域/无碰撞 |
| S4 放置 | 5–8 | 0.5 | 支撑/包容/堆叠稳定 |
| S5 插入 | 3–5 | 0.3 | 插入深度/卡合 |
| S6 关节 | 3–5 | 0.3 | 关节状态/盖子/拉链 |
| S7 拉拔 | 3–5 | 0.4 | 分离/抽出 |
| S8 倾倒 | 5–8 | 0.5 | 内容物转移/无洒出 |
| S9 变形 | 5–10 | 0.4 | 折叠边/塞入深度 |
| S10 序列 | 5–8 | 0.6 | 顺序/类别/全部完成 |

自由空间用长 chunk 省延迟；接触段用短 chunk + 低增益防过冲。第 12 轮的 5 步伺服保留为默认内环，技能卡可覆盖为 3–15。

### 7.4 延迟预算

- 一次 SC-LoRA 前向 + 一次卡片检索；卡片 embedding 可预计算/缓存。
- 目标 p95 `≤1.2×` 官方 WLA baseline；如果 LoRA 合并导致延迟上升，降 rank 或缩短 chunk。
- 不在每个 chunk 内做多次大模型前向；视觉伺服只做轻量几何/图像误差。

### 7.5 合规检查

- 一个 checkpoint：`θ_0 + ΔW`；
- 一个 adapter：`ΔW`；
- 无按任务 ID 加载不同权重；
- 技能图/卡片是配置，不是学习模型；
- 最终提交包只包含一个策略服务。

## 9. 竞赛策略与统计

### 9.1 分数与方差

每任务 100 分：

```text
S = (1/32) Σ_i s_i,  s_i ∈ [0,100]
```

320 trials 下，成功率 `p` 的标准误：

```text
SE = sqrt(p(1-p)/320)
p=0.5 -> 2.8pp
p=0.25 -> 2.4pp
p=0.1 -> 1.7pp
```

因此：

- 小于 3pp 的差异必须用配对设计（同初始状态/同 trial）和 bootstrap 置信区间；
- 单任务通道可以多测，但样本仍有限，不能把 +1–2pp 当结论；
- 优先看步骤分（部分成功）和技能级指标，不只盯最终成功率。

### 9.2 投资组合

```text
priority_s = f_s * r_s * h_s / c_s
```

- `f_s`：技能覆盖任务比例；
- `r_s`：泛化轴失败风险（由 `generalization` 注释和失败库估计）；
- `h_s`：headroom = 1 - 当前技能成功率；
- `c_s`：工程成本（卡片/数据/训练/调试）。

示例判断（定性，不是实测）：

| 技能 | 覆盖 | 风险 | 成本 | 优先级 |
|---|---|---|---|---|
| S4 放置 | 高（多数任务） | 中 | 中 | 最高：先做稳 |
| S5 插入 | 中（5 任务） | 高 | 中 | 高：最后 3 厘米 |
| S6 关节 | 中（5–9 任务） | 高 | 中 | 高：接触密集 |
| S2 抓取 | 高 | 中 | 低 | 高：基础 |
| S7 拉拔 | 低（3 任务） | 中 | 低 | 中：快速收益 |
| S9 变形 | 低（4 任务） | 高 | 高 | 中低：第二梯队 |
| S10 序列 | 中（9 任务） | 中 | 中 | 中：长尾 |

### 9.3 单任务通道

- 每个技能选 2–3 个代表任务：
  - S5：T01、T10、T26；
  - S6：T12、T19、T28；
  - S4：T07、T23、T29；
  - S9：T16、T18；
  - S7：T05、T30；
  - S10：T09、T24。
- 每个代表任务 10 trials，配对 A/B（baseline vs 新方案）；
- 记录成功率、步骤分、时间、失败技能、恢复次数；
- 单任务通道不计分，但用于筛掉坏想法，节省正式 320 trials。

### 9.4 提交顺序

1. **安全基线**：官方 WLA 微调 + 动作限制；尽早提交锁 tie-break。
2. **SC-LoRA**：技能条件化，不加复杂恢复；验证是否比 B1 好。
3. **SC-LoRA + CHUNK-SERVO**：技能级 chunk/增益；验证接触任务。
4. **+ 卡片恢复**：失败恢复/重抓/重对准；验证长尾。
5. **+ 失败库补丁**（可选）：hard negatives；验证是否过拟合单任务通道。

每次只改一个变量；保留回滚；不在正式评测前同时改模型、数据、控制。

### 9.5 不要做

- 不追占位榜单排名；
- 不 32 个任务各训一个策略；
- 不在评测时按任务切换 adapter；
- 不把社区压力场景直接当训练数据；
- 不用 <3pp 的差异宣称显著；
- 不假设仿真成功率能预测真机。

## 10. 实验门 G0–G7

### G0：卡片与技能图完整性

- 32/32 任务至少归属 1 个技能；
- 每个技能至少 2 个任务；
- schema 通过率 100%；
- 双人复核 κ≥0.7；
- 冲突/不可达节点 = 0。
- **杀死**：覆盖 <80%，或关键技能无卡片。

### G1：重标质量

- 边界 F1 ≥0.75；
- 技能分类 acc ≥0.85；
- ECE ≤0.1；
- 每技能 ≥500 高置信片段。
- **杀死**：F1<0.6 或 acc<0.75 -> 回退任务级技能。

### G2：离线动作/技能预测

- 在 held-out episode 上比较 B1/B3/B4；
- 指标：动作 MSE、技能分类、步骤完成预测；
- 通过：B4 相对 B1 提升 ≥5%，且 B2（任务 ID）不解释大部分增益。
- **杀死**：无提升或 B2≈B4（说明只是任务 ID）。

### G3：闭环单任务通道

- 5 个代表任务 ×10 trials，配对 A/B；
- 指标：成功率、步骤分、恢复次数、时间；
- 通过：+3pp 或 +5 分，且无任务退化 >2pp。
- **杀死**：平均退化，或接触任务无改善。

### G4：全任务/子集

- 32 任务 dry run 或 16 任务子集；
- 通过：平均 +2pp；≥8 任务提升；≤2 任务退化 >2pp。
- **杀死**：平均下降。

### G5：泛化轴

- 5 类泛化 ×2 代表任务；
- 通过：≥3 类提升；人为扰动不退化；未见物体不崩。
- **杀死**：人为扰动显著退化（安全/鲁棒性问题）。

### G6：合规与延迟

- 一个 checkpoint、一个 adapter；
- p95 延迟 ≤1.2× baseline；
- 无按任务切换；
- 通过：全部满足。
- **杀死**：需要多模型/多 adapter，或延迟超标。

### G7：用户共创复现

- 20 张社区卡片、10 个压力场景；
- 通过：复现差异 ≤2pp；无安全违规；评审记录完整。
- **杀死**：不可复现或违规。

## 12. 风险与合规

| 风险 | 概率/影响 | 缓解 | 回退 |
|---|---|---|---|
| 技能分类过粗/过细 | 中/高 | G1 粒度消融；以可验证状态变化为准 | 任务级技能 |
| 分割噪声 | 高/中 | 多信号 + 置信度 + 人工抽检 | 只用高置信片段 |
| 技能不平衡 | 高/中 | 技能平衡采样 + 任务平衡 batch | 降采样大技能 |
| LoRA 负迁移 | 中/高 | held-out 验证；TIES/GRAM；早停 | 单多任务 LoRA |
| 合并冲突 | 中/高 | 合并后回归；蒸馏；小 rank | 直接 SC-LoRA |
| 单模型规则 | 低/高 | 一个 checkpoint/adapter；确定性调度 | 删除多 adapter |
| 社区内容质量 | 中/中 | schema + 回放 + 双人评审 | 只用官方数据 |
| 社区安全/隐私 | 低/高 | 声明式内容、去 PII、安全评审 | 关闭社区贡献 |
| 320 trials 方差 | 高/中 | 配对 + bootstrap + 单任务通道 | 不宣称小差异 |
| 延迟超标 | 中/高 | 一次前向、缓存 embedding、短 chunk | 降 rank/缩短 chunk |
| 规则不明确 | 中/高 | 保守解释；向主办方确认 | 最保守提交 |
| 过拟合单任务通道 | 中/中 | held-out 任务/物体；正式评测前不复用 | 回滚补丁 |

**合规底线**：

- 最终一个学习模型/一个 checkpoint；
- 一个 LoRA adapter，不按任务切换；
- 技能图/卡片是配置/控制器，不是第二个模型；
- LoRA 专家只做离线训练/消融；
- 社区贡献只做重标/失败挖掘/压力测试，不直接引入外部训练数据；
- 所有动作受工作空间、速度、夹持力、abort 限制；
- 人为干扰场景优先安全停止/后退。
