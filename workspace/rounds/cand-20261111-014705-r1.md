# 第 51 轮（承接第 50 轮 v14；新灵感循环第 1 轮；本轮灵感：大语言模型 × 通用机器人） · CoStride-Lingua：语义接地证书 × 语言来源信任格 × 证明携带计划 × 能力边界自证（九层架构 v15）

> 承接第 50 轮 v14 CoStride-Distill。v14 用"提议-处置"把蒸馏钉进安全架构：student 只提议、G_exact 精确处置、蒸馏只可近似搜索而绝不可近似评估；又用双足可行性证书与捕获域 MRC 把"可停"升级为"可捕获"，让用户在能力格上共同签署契约。但 v14 仍隐含三个未言明的承重假设：**H11：目标是形式化、单义、静态的——自然语言只是无损前端，语义到形式的翻译被视为理所当然；H12：技能集合封闭可枚举、证书对该任务类别普遍有效、本体固定——通用机器人却面对开放任务分布、长尾与跨本体复用；H13：语言只有一个可信来源（签署用户）——通用机器人会读屏幕、标签、他人语音、网页、设备消息，语言本身就是攻击面**。两个灵感词精确命中：**大语言模型**打破 H11/H13（开放词表、歧义、上下文依赖、自信地胡说、可被提示注入劫持；语言的"理解"是提议，不是真值）；**通用机器人**打破 H12（一具身体服务无穷任务与工具，形态与环境不断变化，无法预先枚举全部技能，且必须知道自己"不会"）。三者耦合出的新问题：**LLM 只能提议"解释与计划"，永远不能签发"接地与认证"；自然语言计划必须携带可机器检查的接地证书与组合证书；语言来源决定它最多能提议什么权威；面对开放任务，机器人必须能证书化地"证明自己不能"，而不是自信地试错。**

## 0. 直觉与动机

**灵感 1（大语言模型 → 语言是提议通道，不是权威通道）**
直觉：v14 已经把"蒸馏只可近似搜索、绝不可近似评估"作为架构红线。把这条不对称原样搬到语义层，就得到本轮的核心：**LLM 只可近似"解释与规划"，绝不可近似"接地与认证"**。LLM 擅长把一句话展开成看似合理的步骤，但它没有资格宣布"这个杯子就是我说的杯子""这个动作在本体上可行""我有能力完成它"。这三件事必须由外部、精确、可审计的机制裁决。LLM 的幻觉由此从"安全事件"降级为"编译错误"：计划编译不过就澄清或拒绝，而不是带着错误语义执行。

**灵感 2（大语言模型 → 证明携带计划 PCP）**
直觉：经典 proof-carrying code 的思想——不可信编译器生成的代码必须自带可检查的证明，宿主只信证明、不信编译器。同理，LLM 是不可信的"语义编译器"：它输出的不是命令，而是**计划 + 假设 + 证书主张**。真正放行的是 `V_pcp` 对组合证书的精确重算：每个技能节点的前置条件、资源/几何/时序一致性、端到端屏障与可行性不变量、来源权威覆盖、能力边界覆盖、本体适用性。LLM 自报的证书只是提示，`V_pcp` 一律重算。于是"计划看起来很对"与"计划被证明可执行"被彻底分开。

**灵感 3（通用机器人 → 能力边界证书：把"我不会"变成一等安全动作）**
直觉：封闭任务集里，"不会"是工程缺口；开放任务分布里，"不会却硬做"才是最大危险。通用机器人不可能预认证所有任务，因此必须能**证明自己不能**：对每个任务-上下文给出 `certified / needs_skill / refuse` 三态，`certified` 带分布内覆盖率保证（选择性预测/保形校准），域外一律拒绝或请求新技能。拒绝不是失败，而是与停机等价的、可审计的安全动作，并附"为什么不会"的见证。能力边界只允许通过"PFV + 真机认证 + 适用域标签"的增长来扩张，LLM 说"我会"不算证据。

**灵感 4（通用机器人 → 跨本体语义幻觉与适用域标签）**
直觉：LLM 的语料以人为中心，它会自然地说"抓住杯柄"而不顾这具身体是双指夹爪、吸盘还是灵巧手；人类视频里的技能被它当成通用真理。这就是**本体幻觉**。解法不是让 LLM 更小心，而是给每张技能证书贴 `EAT=(本体类, 工具, 环境, 传感, 接触 regime)` 标签，跨体复用必须满足标签偏序并重新认证；否则证书视为失效，`δ_xemb` 显式膨胀。语义可以迁移，证书不能白嫖。

**灵感 5（大语言模型 × 安全 → 提示注入即物理攻击，来源格即防火墙）**
直觉：通用机器人会读世界里的文字：门牌、药瓶、便签、屏幕、别人的话。文本一旦能改变计划，环境就能"向机器人下达命令"。因此必须有一张**不可伪造的语言来源信任格**：签署用户 > 认证应用/操作员 > 设备文本 > 开放网络/第三方语音。来源在采集处由传输与身份认证钉死，**绝不由 LLM 自己判断"这句话可信吗"**；LLM 无权提升自己的权威。注入尝试只能污染"提议"，不能越过授权 meet，更不能触碰 PFL/屏障/MRC/审计这些不可委托的根信任。当权威与请求冲突时，机器人不是"灵活变通"，而是澄清或拒绝。

**耦合升级**：在 v14 八层中插入 **L2.2 语义接地与计划编译层（SGC+PCP）**，把 L2 降级为纯"计划提议者"；在根信任处新增 **语言来源信任格与 LPF 防火墙**；L4 守卫增加"计划证书 ∧ 接地证书 ∧ 来源权威"校验；L5/L6 增加接地失败、澄清、拒绝与语义反例。九层 v15：根信任+用户能力格+语言来源格 · L1 几何感知 · L2 语言入口/上下文/记忆/语音（带来源标签） · **L2.2 语义接地与计划编译（SGC/PCP/CLA）** · L2.5 交互安全与共创契约 · L3 关节证书/抽象/决策 · L3.5 动力可行（HVC/CRM） · L4 CAR/Shield/CBG+/KDX/PCP 守卫 · L5 DCL/真机评测 · L6 原型证伪/XFER/LFF。联合决策升级为 `(v_t^*, a_t^*, m_t^*, q_t^*, ι_t, κ_t, ς_t)`，`ς`=接地状态/来源权威/能力边界三态。

## 1. 形式化定义（增量：定义 87–93）

**定义 87（语言来源信任格与指令权威）**
来源集 `S={signed_user, authenticated_app, operator, on_device_text, open_web, third_party_speech, self_generated}`，信任格 `L_src=(S,⊑)`；授权映射 `π: S→2^{𝒜}`（`𝒜` 为 v14 能力格）。语句 `x` 携带采集处钉死的来源 `p=prov(x)`（由签名信道/认证传感器给出，**不可由 LLM 推断或修改**）与权威 `a(x)=π(p) ⊓ a(ctx)`。`x` 请求条款 `c` 合法当且仅当 `c ⊑ a(x)` 且不触根信任。**提示注入**定义为：存在来源 `p` 的语句试图请求超出 `π(p)` 的权威，或诱导系统修改 PFL/屏障类别/MRC/审计；一律拦截并记账。关键不变式：`LLM 永远不能成为自己来源与权威的裁判`。

**定义 88（语义接地证书 SGC）**
自然语言目标 `x`、世界模型 `W`（场景图 + 能力模型 + 上下文）。接地候选 `g=(R,U,T,A,P)`：指代 `R`、单位/数量 `U`、时序/因果 `T`、affordance/前置条件 `A`、计划骨架 `P`。证据 `E` 来自感知与知识库的支持/反驳对。证书 `γ_s=(h(x), g, E, Ass, μ, ver)`，`μ` 为逐槽歧义度。接地器 `Γ_ground:(x,W)→(γ_s | Clarify)`。**忠实性**要求：对语义等价改写 `x'∈Equiv(x)`、否定与量词/辖域变体，接地约束必须保持等价或能被检测为矛盾（paraphrase/negation/scope 不变性）；`μ` 只能来自外部检查（多解析器分歧、场景支持度、跨模型一致性），**LLM 自报置信度不是证据，且 LLM 不得给自己的接地打分**。`max μ>τ_amb` 或两个同支持度接地冲突 → 触发澄清义务（定义 92）。

**定义 89（证明携带计划 PCP）**
`Π=(DAG, {γ_i}, γ_comp, h)`：DAG 节点为类型化技能调用（参数化），每节点携带其 v14 技能证书（屏障/可行性/PFL）；`γ_comp` 是组合证书，证明：(i) 每个节点前置条件由前驱或初始状态建立；(ii) 资源/几何/时序一致；(iii) 沿所有（或已界定集合的）交错，端到端屏障与可行性不变量成立；(iv) 来源权威覆盖 DAG 所需权威；(v) 每节点在能力边界内（定义 90）；(vi) 本体适用（定义 91）。验证器 `V_pcp` 是精确的、成本被认证的，**执行当且仅当 `V_pcp(Π)=⊤`**。LLM 可生成 DAG 与证书主张，但 `V_pcp` 一律重算；幻觉 = 类型/验证错误。

**定义 90（能力边界证书 CBC 与认证式增长）**
任务-上下文 `τ`。能力映射 `K: T×C→{certified, needs_skill, refuse}`，满足：在认证分布内 `P(success | certified) ≥ 1−α_comp`（选择性预测/保形校准），分布外必须输出 `needs_skill/refuse`。扩张单调且受限：新技能只有经 v14 PFV 证伪 + 真机认证 + 适用域标签后才可入 `K`；LLM 的"我能"不构成证据。`refuse` 必须附见证 `why(τ)`（缺技能/域外/歧义/本体不适），可审计。**拒绝与请求帮助是一等安全动作，不是失败。**

**定义 91（本体适用域标签 EAT 与跨体再证）**
每张技能证书携带 `EAT=(body_class, tool, environment, sensor_suite, contact_regime)`。适用性 `xemb_ok(cert, current) := current.tag ⊑ cert.EAT`（按特异性偏序）。不满足则证书视为**失效**，必须重新认证并把跨体传输缺口 `δ_xemb` 计入部署置信。EAT 是"本体幻觉"的结构性防线：人类语料里的技能不得凭语言相似性直接搬到另一具身体。

**定义 92（澄清义务与承诺协议 CLA）**
触发澄清的充分条件：`max μ>τ_amb`；来源权威冲突（两个高权威源矛盾）；接地结论与能力/可行性矛盾；动作不可逆且存在任何残余歧义。澄清必须问**最小充分问题**（在问题候选集上最大化单位成本期望信息增益），禁止"最佳猜测后静默执行"。用户回答是携带自身来源的**新语句**，走同一接地与授权流程并更新 `γ_s`、记账。由此"问而不是猜"成为可认证行为。

**定义 93（账本 CCL+++ 与九源归因）**
在 CCL++ 上追加：语言来源与权威判定、接地证书/接地失败、澄清请求与答复、拒绝/needs_skill、技能增长与 EAT 事件。DDA 归因扩为**九源**：感知/关节/边界/意图/接触/传输/动力/蒸馏/**语义（接地·来源·能力边界）**。任一语义置信折损显式入账并参与抽象、速度缩放与澄清阈值，不得静默吸收。

## 2. 新增产出与既有 IP 升级

**IP-91 LPF（Language Provenance Firewall）**：语言来源信任格 + 不可伪造 provenance + 权威 meet + 注入拦截；LLM 无权自判来源。
**IP-92 SGC（Semantic Grounding Certificate）**：指代/单位/时序/affordance 接地证书；外部证据与多解析器；paraphrase/negation/scope 不变性探针。
**IP-93 PCP（Proof-Carrying Plan）**：不可信 LLM 生成计划+假设+证书主张；`V_pcp` 精确重算组合证书；幻觉=编译错误。
**IP-94 CBC（Competence Boundary Certificate）**：三态能力边界 + 保形覆盖 + 拒绝见证 + 认证式增长。
**IP-95 EAT（Embodiment Applicability Tag）**：技能证书适用域标签；跨体复用必须再证并膨胀 `δ_xemb`。
**IP-96 CLA（Clarification Obligation）**：歧义/来源冲突/不可逆动作强制最小充分澄清，禁止静默猜测。

**既有 IP 升级**
IP-80 SIG：意图后验乘上"已接地承诺 × 来源权威"证据，LLM 自报置信不入后验。
IP-82 IPC：协议新增"澄清-答复"与"拒绝"状态转换。
IP-74 HTD-Cert：DAG 由 LLM 提议，但节点边界须经 PCP 编译；分解不再被当作权威。
IP-75 ASC：抽象可行性加入 `ς`（接地/来源/能力）门；未知即细化或拒绝。
IP-89 KDX：守卫处置对象从候选动作升级为"候选动作 + 计划证书"，`G_exact` 增加 `V_pcp` 结果校验。
IP-87 HVC：可行性剪辑作用于**已接地**参数，单位/指代未定前禁止任何速度/幅值放行。
IP-83 PFV：语义对抗原型——改写/否定/辖域/指代歧义/注入文本/跨体描述注入。
IP-84 XFER：传输缺口增加 `δ_xemb`（本体保真）维度。
IP-77 DDA：八源 → 九源（+语义）。
IP-61 DCL：新增接地失败、澄清、拒绝、越权来源、技能增长五类样本。
IP-62 CCA：新增提示注入、权威升级、欺骗性澄清、跨体语义冒充红队。
IP-51 CAR：守卫加"PCP 通过 ∧ 接地证书有效 ∧ 来源权威覆盖"。
IP-45 总线：新增 language-provenance / grounding-state / competence-state / clarification 话题。
IP-86 UCC：签署用户仍是最高来源，但仍受能力格与不可委托约束；共创条款必须先接地再签署。
IP-72 RRP：e-process 纳入接地/来源/能力边界证据。
IP-76 CCL：升级为 CCL+++（定义 93），仍只追加。

## 3. 算法骨架

每个宏周期：
1. 读目标、证书 `C_t`、租约、`CCL+++`、契约版本哈希与来源标签；任一失效 → fail-closed。
2. LPF：在采集处钉死 provenance，计算权威 `a(x)=π(p)⊓a(ctx)`；越权请求只当"观测"不当"命令"，注入入账。
3. LLM 只做提议：输出带假设、歧义标注与证书主张的计划骨架，禁止直接执行。
4. SGC 接地：多解析器 + 场景/能力证据；跑 paraphrase/negation/scope 探针；歧义超阈或来源冲突 → 触发 CLA，问最小充分问题。
5. PCP 编译：技能 DAG 逐节点查精确技能证书、EAT 与能力边界；组合证书由精确规则合成；`V_pcp` 重算。
6. CBC：每节点三态判定；`needs_skill` → 技能合成（离线/异步）；`refuse` → 附见证停下或请求人工；LLM 的"我能"不入证据。
7. 通过后进入 v14 主链：KDX 提议-处置、HVC 可行性复核（`B_v≥0` 与 time-to-boundary）、CRM 捕获。
8. `G_exact` 复核边界蕴含 ∧ 屏障 ∧ 可行性 ∧ PFL ∧ 协议共识 ∧ 版本匹配 ∧ PCP ∧ 来源权威；全过才执行并追加 CCL+++。
9. 若实测违反或接地失败：DDA 九源归因，选最早安全点再分解/重接地/再蒸馏/再认证；必要时 CRM。
10. 离线/并行：PFV 用语义对抗原型证伪；LFF 学习薄弱区；新反例回灌 DCL/CCA 并共蒸馏 student、接地器与能力模型；任何路径不可行 → 澄清/拒绝/人工接管/保护姿态，绝不绕过 L2.2 与精确守卫。

## 4. 本轮最大风险

**一句话**：整套"LLM 只提议、接地与认证只由精确机制裁决"的不对称，悬挂在一个新的承重假设上——**接地器 `Γ_ground` 的忠实性与能力边界 `CBC` 的校准必须对开放世界成立**；一旦场景/能力模型本身不完整，系统会生成"证书齐全但语义错了"的**有证书的胡说（certified nonsense）**，而一旦来源身份可被伪造、LLM 又悄悄参与判断自身权威，提示注入就会变成物理攻击路径，因此接地必须用改写/否定/辖域/反事实持续证伪、能力边界必须做分布无关校准并保留显式 unknown/refuse、来源必须根植于不可伪造身份且根信任不可委托。

## 2. 关键算法 伪代码

### IP-91 LPF（来源防火墙）
```
def ingest(utterance, channel):
    p = channel.provenance()                 # 传输/身份认证处钉死，LLM 不可见不可改
    a = lattice_meet(pi(p), capability_now())# 有效权威 ≤ 来源范围
    return Utterance(text=utterance, prov=p, authority=a, sig=channel.signature())

def authorize(u, needed_clause):
    if touches_root_trust(needed_clause):     # PFL/屏障/MRC/审计 不可委托
        ledger_append_plus(now(), 'authority_denied', u.prov, needed_clause)
        return False
    if not lattice_leq(needed_clause, u.authority):
        ledger_append_plus(now(), 'injection_suspect', u.prov, needed_clause)
        return False                          # 只可作"观测"，不可作"命令"
    return True
```

### IP-92 SGC（语义接地证书）
```
def ground(x, W, parsers, tau_amb):
    cands = [p.parse(x, W) for p in parsers]        # 多个独立解析器，非单一 LLM
    for g in cands:
        g.E = collect_support(g, W)                 # 场景图/能力库/上下文支持与反驳
    mu = slot_disagreement(cands) + scene_unsupported(cands) + unit_conflicts(cands)
    if max(mu) > tau_amb or conflicting_support(cands):
        return Clarify(minimal_question(cands, W))  # 触发定义 92
    g = select_best_supported(cands)
    if not invariance_probe(x, g, parsers):         # 改写/否定/辖域/量词探针
        return Clarify(minimal_question(cands, W))
    return Cert_s(x_hash=h(x), g=g, E=g.E, Ass=g.assumptions, mu=mu, ver=next_ver())
    # LLM 的自报置信不进入 mu；LLM 不给自己打分
```

### IP-93 PCP（证明携带计划编译与验证）
```
def compile_plan(goal_cert, proposer, skill_lib, ctx):
    dag = proposer.propose_dag(goal_cert, ctx)       # 不可信 LLM：DAG + 假设 + 证书主张
    for node in dag.nodes:
        cert = skill_lib.lookup_exact(node.skill, node.params)
        if cert is None:
            return NeedsSkill(node, why='missing_skill')
        if not xemb_ok(cert, ctx.body):              # 定义 91
            return NeedsSkill(node, why='embodiment_mismatch')
        if not competence_ok(node.task, ctx) == 'certified':   # 定义 90
            return NeedsSkill(node, why=competence_reason(node, ctx))
        if not provenance_covers(goal_cert.prov, node.authority):
            return Reject(node, why='authority_insufficient')
        node.cert = cert                             # 精确查表，不用 LLM
    comp = compose_certificates(dag, ctx)            # 精确规则合成，逐项重算
    if not V_pcp(dag, comp, ctx):                    # 成本被认证的精确验证
        return Reject(dag, why='composition_failed')
    return PCP(dag=dag, comp=comp, h=hash(goal_cert, skill_lib, ctx))
```

### IP-94 CBC（能力边界证书）
```
def competence(task, ctx, calib):
    if ood(task, ctx):
        return ('refuse', why='out_of_distribution')
    s = competence_model(task, ctx)                  # 离线训练，真机标定
    lo, hi = calib.conformal_interval(s, alpha=ALPHA_COMP)
    if lo >= CERT_THRESH:
        return ('certified', None)
    if hi < CERT_THRESH:
        return ('refuse', why='low_competence')
    return ('needs_skill', why=nearest_gap(task, ctx))

def accrete_skill(skill, pfv, real_robot, eat):
    if not pfv.no_violation(skill) or not real_robot.passed(skill):
        return 'reject'                              # LLM 说"我会"不算证据
    skill_lib.add(skill, cert=real_robot.cert, eat=eat)   # 只增不减、带适用域
    return 'accepted'
```

### IP-96 CLA（澄清义务）
```
def must_clarify(gamma, node):
    return (max(gamma.mu) > TAU_AMB
            or provenance_conflict(gamma)
            or contradicts_capability(gamma, node)
            or (irreversible(node) and any(mu > 0 for mu in gamma.mu)))

def minimal_question(cands, W):
    return argmax_q E_IG(q, cands, W) / cost(q)      # 最小充分、信息增益/成本最大
```

### IP-73 JCPS（v15：语言提议 → 接地 → 证明 → 处置）
```
def joint_costride_schedule(goal, C_t, leases, energy, q_prev, omega, b, kappa_c):
    u = ingest(goal.text, goal.channel)              # 来源钉死
    if not authorize(u, goal.needed_clause):
        return ('clarify_or_refuse', reason='authority')
    gamma = ground(u.text, world(), parsers(), TAU_AMB)
    if isinstance(gamma, Clarify):
        return ('clarify', gamma.question)           # 不猜、不执行
    plan = compile_plan(gamma, llm_proposer, skill_lib, ctx())
    if isinstance(plan, (NeedsSkill, Reject)):
        return ('needs_skill_or_refuse', plan.why)   # 拒绝是一等安全动作
    if not viability_ok(current_z(), current_mode(), kappa_c):
        return ('crm', biped_mrc(current_state(), current_mode(), student))
    b = sharpened_intent(b, gamma, u.prov, omega)
    sigma = intent_scale(b)
    for node in plan.dag.toposort():
        cands = student.propose(o, ctx, node)        # 仍只是提议
        for cand in cands:
            if guard.exact_check(cand, h=plan.h) and V_pcp(plan):
                execute(cand)
    ledger_append_plus(now(), 'pcp_executed', plan.h)
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| LPF | O(|S|) 权威 meet | O(|来源标签|) | 来源不可伪造；越权/触根信任即拒；LLM 不参与权威判定 |
| SGC | O(k·parse + |W|·|g|) | O(|E|) | 多解析器+外部证据；paraphrase/negation/scope 探针；超阈必澄清 |
| PCP 编译 | O(|DAG|·lookup + compose) | O(|DAG|) | 逐节点精确查表 + 组合证书重算；LLM 主张不采信 |
| V_pcp | ≤ τ_pcp（离线认证） | O(|DAG|+certs) | 成本被认证 + 看门狗；失败即拒 |
| CBC | O(1) 推理 + 校准查表 | O(校准集) | 分布内覆盖 ≥1−α_comp；OOD 必 refuse |
| EAT | O(1) 偏序判定 | O(1) | 标签不匹配即证书失效，必须再证 |
| CLA | O(|问题候选|) | O(|cands|) | 歧义/冲突/不可逆强制澄清；禁静默猜测 |

**正确性定理（Grounded, Provenance-Bounded, Competence-Bounded Soundness）**
在 v14 假设 (A1)–(A12) 之上新增：**(A13)** 接地器 `Γ_ground` 对 `Equiv(x)` 与否定/辖域变体忠实，其错误以概率 ≤`α_sem` 发生；`μ` 不低估真实歧义；**(A14)** 能力边界 `CBC` 满足分布内覆盖 `P(success|certified)≥1−α_comp`，域外必弃权；**(A15)** EAT 标签可靠，跨体复用均经再证，`δ_xemb` 不被低估；**(A16)** 语言 provenance 不可伪造、LPF 位于所有语言入口且 LLM 不能绕过或自判权威。则沿路径、交互序列、步态相位与计划 DAG，
`P(∀t≤T: z(t)∈Z_safe) ≥ 1 − Σ_i α_i − Σ_i ε_hand,i − α_lease − α_intent − α_user − α_viable − α_cap − Σ_ℓ δ_{ℓ→d} − α_sem − α_comp − δ_xemb`；
且**语义与能力误差不进入放行标准**：LLM 的解释/规划/自我能力声称误差只能提高澄清率、拒绝率与 needs_skill 率（可用性/效率损失），因为执行要求 `V_pcp` 精确通过 ∧ `G_exact` 精确求值通过 ∧ 来源权威覆盖。**拒绝与澄清是安全动作**：开放任务下"未认证即不做"使开放世界风险被显式挡在门外，而非被 LLM 自信地吞入。这仍是**条件保证**：`Γ_ground` 的忠实性、`CBC` 的校准、EAT 的充分性、来源身份的可信性是新的信任锚，由 PFV 的语义对抗原型、CCA 的注入红队与 DCL 的接地/拒绝日志持续证伪，不在定理覆盖范围内。

回退策略：E139 注入漏拦 → 冻结所有非签署来源的指令权、审计来源认证链、收紧 `π`；E140 certified nonsense > 0 → 立即停止执行该类计划、对场景/能力模型追加语义反例、提高 `τ_amb`、扩多解析器；E141 幻觉漏拒 → 收缩 LLM 提议权（只给单步、禁长程）、加 `V_pcp` 覆盖不变量；E142 误认证 > 0 → 降 `CERT_THRESH`、扩校准集、对域外一律 refuse；E143 本体幻觉 → 禁止跨体复用、全部再认证、提高 `δ_xemb`；E144 成功率或信任不足 → 缩小开放任务域或增加反问，绝不以降低守卫换流畅。

## 6. 本轮最大风险

**一句话**：整套"LLM 只提议、接地与认证只由精确机制裁决"的不对称悬挂在 (A13)/(A14) 两个新锚上——一旦接地器对开放世界不忠实、能力边界校准失效，系统会产生"证书齐全但语义错误"的有证书的胡说，而一旦语言来源可伪造或 LLM 被允许参与自身权威判断，提示注入就会成为物理攻击路径；因此接地必须用改写/否定/辖域/反事实持续证伪，能力边界必须分布无关校准并保留显式 unknown/refuse，来源必须根植于不可伪造身份且根信任不可委托。
