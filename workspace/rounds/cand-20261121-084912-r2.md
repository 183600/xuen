# 第 2 轮（新灵感循环第 2 轮；本轮灵感：「平衡控制」×「成本控制」）

> **基线**：上一轮（灵感「大语言模型」×「机器人」×「智能体」）MetricVoiceGauge-NCD-HUTDH-v17（定义 657–674；引理 137–142；实验 E691–E710）。
> 本轮纪律：**平衡是资产负债表（存量），成本是现金流量表（流量），证书是审计**。不推倒 v17：v17 的 CLP/S2C/HCG/PSV/APS/AMC 与 v16 的 BTS/TRM/WBC/CSC/NCS/MCA/WCB 及 v13→v6 全部保留。本轮新增六个组件——BRC（平衡储备证书）、CCL（成本账本）、BCA（平衡-成本准入）、SRA（偿付与回补仲裁）、PBS（帕累托平衡-成本选择器）、CCA（证书成本核算器）——一律以**纯过滤/选择元**接入 v17 之上，失效即严格退回 v17（引理 143、148），再沿 v17→v16→…→v6 退化链退回。本轮只做三件事：把"安全"改写为**可偿付的储备**、把"证书"改写为**有价格的资源**、把"规划"改写为**预算约束下的效率选择**。

## 0. 直觉与动机

**灵感 1（平衡控制 → 安全不是状态，而是储备）**
直觉：经典平衡控制（CoM/ZMP → 捕获点 → 迈步）的本质不是"站进安全区"，而是"始终保有回到安全区的余量"。v17 的计划证书 `PC(π)` 只保证"每个节点后置非空、每条缝非空"，也就是**此刻**在安全区内；它完全不保证"执行完还留有余量应付下一次扰动"。核心创新：**平衡储备证书（Balance Reserve Certificate, BRC）**——用控制屏障函数（CBF）`h_bal(x) ≥ 0` 定义平衡安全集，把储备定义为 `ρ_bal = h_bal(x)`；计划必须保证全程 `h_bal ≥ h_min`，且终态 `h_bal ≥ h_min + h_recover`（留出执行 safe-stop 的余量）。关键反直觉点：**把每个节点都推到安全区最深处（最大化即时 margin）反而更不安全**——因为不迈步、不回补储备，储备会被扰动持续消耗，最终一次性崩溃。安全是**动态预算**，必须被主动补充，而补充本身有成本；因此"平衡"的正确对象是储备的耗散-回补动力学，不是静态 margin。

**灵感 2（成本控制 → 每份证书都有价格，且计算与储备可互换）**
直觉：证书不是免费的。PSV 每缝复验、HCG 打分、CBF 求解都在吃实时预算；保守 margin 在吃能量、热余量与机会。100 条缝 × 0.05ms = 5ms，占 20ms 控制周期的 25%——你是在"证明安全"而不是"完成任务"。核心创新：**证书成本核算器（Certificate Cost Accountant, CCA）**，把认证强度 `θ_cert=(α, margin_sc, 复验频率, 缝抽样数)` 与认证成本 `c_cert(θ)` 显式记账。关键反直觉点有两层：(a) **更强的证书可能经济上非理性**——证书强度存在成本最优值，不是越大越好；(b) **计算与物理储备是替代品**——你无法廉价验证的缝，可以用更大的平衡储备去"缓冲"，每一单位省下的认证计算可经一个可标定的**汇率**折算成需追加的物理储备。于是控制器可以在"多算"与"多留余量"之间选更便宜的一种来买同一水平的安全。

**灵感 3（机器人 → 二者合一：存量与流量）**
直觉：把机器人看成一间公司。平衡储备 `ρ_bal` 是**资产负债表上的权益（存量）**；成本率 `ċ_cost` 是**现金流量表上的支出（流量）**；证书系统是**审计**。公司可以今天很安全（权益充足）却因现金流断裂而明天倒闭；机器人也可以此刻 margin 很大却因成本不可持续而失去回补能力。核心创新：**平衡-成本准入（Balance-Cost Admission, BCA）+ 偿付与回补仲裁（Solvency & Recovery Arbiter, SRA）**：一个计划不仅要在 v17 意义下"安全"，还要"负担得起"，并且执行完之后仍然"偿付得起一次安全停机"。关键反直觉点：**计划的价值不只取决于它能做什么，还取决于它让你在之后还能做什么**——一个把储备吃干的高价值计划，可能严格劣于一个低价值但留有余量的计划。

**三者如何统一**
统一为 **v17 语言层之上的资源治理层**：v17 回答"哪些语言计划能被安全编译与执行"（`Exec_v17`），v18 回答"在这些安全计划里，哪些此刻负担得起、执行完仍偿付得起、且成本效率最高"（`Exec_v18`）。BRC 管**平衡存量**，CCL 管**成本流量**，BCA 是**联合准入闸门**，SRA 管**偿付底线与回补**，PBS 管**准入集内的效率选择**，CCA 管**认证预算与计算-储备互换**。共享状态 `ζ_rc=(B_tick, m*, h*, ρ_bal, ρ_cost, h_min, θ_cert, c_budget, plan_candidates, cost_model, mode_rc)`。**BRC 回答"还剩多少平衡本钱"，CCL 回答"还剩多少成本本钱"，BCA 回答"这个计划会不会让你破产"，SRA 回答"什么时候必须停下来回血"，PBS 回答"在负担得起的计划里哪个最划算"，CCA 回答"安全该用计算买还是用余量买"**。六者不是补丁，而是"计量—准入—偿付—选择—核算"的资源治理链。

## 1. 研究问题（轮次升级版）

- **Q1（储备的证书语义）**：如何选取 CBF `h_bal` 使"储备非耗尽"可被逐节点、逐缝地证明？多平衡指标（支撑多边形、ZMP、捕获点、摩擦锥、力矩/热余量）如何取 min 而不被单一指标掩盖？`h_min` 与 `h_recover` 如何与 v17 的 `margin_sc` 联合标定？
- **Q2（成本证书与方差）**：成本-to-go 上界 `Ĉ_n` 如何在接触/负载/热漂移下保持"高概率上界"？预测-实际方差如何触发上界加严而不误杀活性？能量、热、算力三种不可比成本如何合成一个可加的记账单位？
- **Q3（偿付不变集与回补）**：如何定义并保证偿付不变集 `K` 前向不变？回补动作（迈步/原地踏步/下蹲）本身有风险，如何证明"回补不引入新风险"？中断任务的收益-成本如何比较（迟滞）？
- **Q4（认证预算与计算-储备汇率）**：`c_cert(θ)` 与安全水平 `R(θ, h_min)` 如何在线标定？等安全水平集上的汇率如何估计与随漂移更新？预算不足时如何在 `Θ_safe` 内退化而不越过 v16 安全地板？

## 2. 设计原则（在 P28–P30 基础上新增 P31–P33）

**P31 储备而非状态律（Certify the Reserve, Not the State）**
每个节点/计划的证书必须包含储备约束：`BRC(π) = (∀t: h_bal(x_t) ≥ h_min) ∧ (h_bal(x_end) ≥ h_min + h_recover)`。只证明"后置非空/缝非空"（v17 的 `PC`）是不够的；必须证明"沿轨迹储备不耗尽，且终态留有恢复余量"。**平衡指标取多指标 min**，禁止用平均值或加权和掩盖最弱项。

**P32 偿付优先律（Solvency Before Value）**
任何计划在执行前必须通过偿付检查：执行后仍能负担并安全执行一次 certified safe-stop，即 `ρ_bal' ≥ h_min + h_recover` 且 `ρ_cost' ≥ c_need`。价值 `V(π)` 只在**偿付可行**的准入集内比较；当回补的边际收益超过继续任务的边际价值时，SRA 必须中断任务执行回补。**安全停机是永远可负担的最后一份资产。**

**P33 认证预算律与计算-储备互换律（Certification Budget & Compute–Reserve Fungibility）**
认证强度只能在 `Θ_safe`（引理 137 仍成立的参数族）内选择，且 `c_control + c_cert(θ) + c_plan ≤ T_loop`。在固定安全水平 `R(θ,h_min)=R_0` 上，认证计算与物理储备可互换：`dh_min/dc_cert < 0`。CCA 选择等安全集上经济代价最小的点。**任何放宽认证参数的行为都必须由追加的物理储备补偿，且放宽不得越出 `Θ_safe`。**

## 3. 与基线的接口（如何退化）

- BRC 失效（CBF 求解不可用）⇒ 用固定静态余量 `h_min^fix` 取代储备证书——**等价 v17 + 固定安全余量**；
- CCL 失效（成本模型损坏）⇒ 成本视为 0、只保留 safe-stop 成本储备 `c_need`——**等价 v17（可能超额执行但仍安全）**；
- BCA 失效 ⇒ 直接放行 v17 准入集——**等价 v17**；
- SRA 失效 ⇒ 每个 epoch 末强制插入一次 safe-stop——**等价 v16 单步执行（更保守）**；
- PBS 失效 ⇒ 按 v17 的 `V(π)` 最大者选择——**等价 v17**；
- CCA 失效 ⇒ 固定最保守 `θ_cert`——**等价 v17 保守配置**；
- 六者全失效 ⇒ MetricVoiceGauge-NCD-HUTDH-v17，再沿 v17→v16→…→v6 退化链退回；
- **安全继承**：BRC/CCL/BCA 只追加合取约束，PBS 只在准入集内选择，SRA 只触发 v16 认证的恢复动作，CCA 只在 `Θ_safe` 内换参数。它们都不能新增授权或放宽 v16 锚集；`Exec_v18 ⊆ Exec_v16` 由引理 143 保证。**注意**：CCA 的放宽可能使 v18 相对"固定参数 v17"不是子集（这正是它恢复活性的方式），但始终含于 `⋃_{θ∈Θ_safe} Exec_v17(θ) ⊆ Exec_v16`——放宽只提升活性，不越过安全地板。

## 4. 预期贡献

1. **储备化安全**：首次把"节点/缝非空"的计划证书升级为"沿轨迹储备不耗尽 + 终态可偿付"的储备证书，证明平衡是动态预算而非静态 margin，给出"最大化即时 margin 反而不安全"的形式化反例；
2. **偿付不变集**：形式化"执行完仍能负担安全停机"的生存性约束，证明 `K` 在 v18 策略下前向不变，使"安全停机"成为永续可负担的底线资产；
3. **证书成本核算与计算-储备互换**：把认证本身当资源消费者，给出认证预算约束、成本最优认证强度、以及"计算 ↔ 物理储备"的可标定汇率，直接消解 v17 的"过度保守"与"token/算力成本"两大风险；
4. **纯过滤式资源治理**：BCA/PBS/SRA 只减不增、只在 `Θ_safe` 内换参，给出 `Exec_v18 ⊆ Exec_v16` 的安全地板不变式，把"成本控制"从"削减任务"改写为"在等价安全下选最便宜的买法"；
5. **平衡-成本统一记账**：用"存量/流量"把平衡储备与成本预算统一为一张可审计的资产负债表 + 现金流量表，为长程任务提供"既不倒也不破产"的可验证判据；
6. **六层分离**：v12 管"允许什么"，v13 管"时限内实现多少"，v15 管"技能如何扩散"，v16 管"全身行为如何按里程碑执行"，v17 管"哪些语言计划被编译与调度"，v18 管"在预算与偿付下执行哪个"，用 `Exec_v18 ⊆ ⋃Θ_safe Exec_v17(θ) ⊆ Exec_v16 ⊆ …` 把资源、语言、行为、路线、动力学、实时全解耦；E711–E730 覆盖储备、偿付、成本上界、方差加严、互换、预算、过滤性、效率、回补、端到端与消融。

## 5. 本轮最大风险

**一句话**：储备证书与成本证书都建立在"未来消耗与成本-to-go 的上界估计"之上，而新颖计划、模型失配或对抗扰动可以让真实消耗远超估计，使系统在账面上偿付充足、实际储备已为负——即成本/平衡模型的外推误差把"偿付保证"悄悄变成了"虚假会计"。

# IP-415 Balance Reserve Certificate：储备而非状态
class BalanceReserveCertificate:
    def __init__(self, h_bal, h_min, h_recover, horizon, disturbance_bound):
        self.h = h_bal                 # CBF: X -> R, 安全集 {h>=0}
        self.h_min = h_min             # 运行储备下限
        self.h_rec = h_recover         # safe-stop 所需储备
        self.H = horizon
        self.w = disturbance_bound     # 鲁棒最坏扰动消耗率

    def certify_node(self, x, node):
        # 区间 / CBF 前向可达：沿节点策略取最坏储备
        traj = self.h.worst_case_trajectory(x, node.policy, self.H, self.w)
        rho_min = min(self.h(xx) for xx in traj)
        rho_end = self.h(traj[-1])
        ok = (rho_min >= self.h_min) and (rho_end >= self.h_min + self.h_rec)
        return ok, rho_min, rho_end

    def certify_plan(self, x, nodes):
        for n in nodes:
            ok, rmin, rend = self.certify_node(x, n)
            if not ok:
                return False, ('BAL_FAIL', n)
            x = n.expected_post(x)     # 名义后置状态传播
        return True, ('OK', self.h(x))


# IP-416 Cost-Centric Ledger：成本-to-go 上界 + 方差加严
class CostCentricLedger:
    def __init__(self, cost_model, budget_rate, reserve_cost, cost_reserve_need):
        self.model = cost_model
        self.B = budget_rate           # 成本率上限
        self.rho_cost = reserve_cost   # 剩余成本预算
        self.c_need = cost_reserve_need
        self.tau_var = 0.2

    def cost_to_go_upper(self, x, node):
        c_hat = self.model.integrate_upper(x, node.policy, node.horizon)
        sigma = self.model.variance(node.fingerprint)
        return c_hat + self.model.kappa(sigma) * sigma   # Ĉ = ĉ + κ(σ)·σ

    def certify_plan(self, x, nodes):
        c_hat, H = 0.0, 0.0
        for n in nodes:
            c_hat += self.cost_to_go_upper(x, n)
            H += n.horizon
            x = n.expected_post(x)
        affordable = c_hat <= self.rho_cost - self.c_need   # 留出 safe-stop 成本
        rate_ok = (c_hat / max(H, 1e-9)) <= self.B
        return (affordable and rate_ok), c_hat

    def observe(self, node, predicted, actual):
        self.model.update(node.fingerprint, predicted, actual)
        rel = abs(actual - predicted) / max(abs(predicted), 1e-9)
        if rel > self.tau_var:
            self.model.degrade_trust(node.fingerprint)   # 方差超限 -> 上界加严


# IP-417 Balance-Cost Admission：只减不增的联合闸门
class BalanceCostAdmission:
    def __init__(self, psv, hcg, brc, ccl, sra):
        self.psv, self.hcg, self.brc = psv, hcg, brc
        self.ccl, self.sra = ccl, sra

    def admit(self, pi, nodes, x, m_star, h_star):
        if not self.psv.verify(nodes)[0]:         return False, ('SEAM', None)
        if not self.hcg.accept(pi, x, self.psv):  return False, ('HCG', None)
        ok_b, info_b = self.brc.certify_plan(x, nodes)
        if not ok_b:                              return False, ('BAL', info_b)
        ok_c, c_hat = self.ccl.certify_plan(x, nodes)
        if not ok_c:                              return False, ('COST', c_hat)
        if not self.sra.solvent_after(x, nodes):  return False, ('SOLVENCY', None)
        return True, c_hat


# IP-418 Solvency & Recovery Arbiter：偿付底线 + 回补
class SolvencyRecoveryArbiter:
    def __init__(self, brc, ccl, recovery_maneuver, hysteresis):
        self.brc, self.ccl = brc, ccl
        self.recover = recovery_maneuver   # 一个 v16 认证的 safe-stop/原地踏步
        self.hys = hysteresis

    def solvent_after(self, x, nodes):
        x_end = nominal_execute(x, nodes)
        ok_b, _ = self.brc.certify_node(x_end, self.recover)
        ok_c, _ = self.ccl.certify_plan(x_end, [self.recover])
        return ok_b and ok_c

    def maybe_interrupt(self, x, rho_bal, rho_cost, plan_value):
        # 回补的边际收益 > 继续任务的边际价值则中断（带迟滞）
        gain = self.recover.reserve_gain(x) - self.recover.cost(x)
        return gain > plan_value + self.hys


# IP-419 Pareto Balance-Cost Selector：效率选择 + 迟滞
class ParetoBalanceCostSelector:
    def __init__(self, lam, hysteresis):
        self.lam, self.hys = lam, hysteresis
        self.current = None

    def score(self, cand):
        pi, nodes, V, c_hat = cand
        return V - self.lam * c_hat        # 或 V / max(c_hat, eps)

    def select(self, admitted):
        if not admitted:
            return None
        best = max(admitted, key=self.score)
        if self.current is not None and self.score(best) - self.score(self.current) <= self.hys:
            return self.current            # 迟滞：不轻易切换
        self.current = best
        return best


# IP-420 Certificate Cost Accountant：认证预算 + 计算-储备互换
class CertificateCostAccountant:
    def __init__(self, t_loop, c_control, safe_family, risk_model, price_compute, price_reserve):
        self.T, self.c_ctrl = t_loop, c_control
        self.family = safe_family          # Θ_safe
        self.R = risk_model
        self.pc, self.pr = price_compute, price_reserve

    def budget(self, c_plan):
        return self.T - self.c_ctrl - c_plan

    def choose(self, c_plan, R0):
        budget = self.budget(c_plan)
        best = None
        for theta in self.family:
            c = self.cert_cost(theta)
            if c > budget:
                continue
            h_min = self.R.required_reserve(theta, R0)   # 等安全集：认证越弱，储备越厚
            econ = c * self.pc + h_min * self.pr
            if best is None or econ < best[3]:
                best = (theta, h_min, c, econ)
        if best is None:                                  # 全超预算 -> 最保守 + 最大储备
            theta = min(self.family, key=self.cert_cost)
            return theta, self.R.required_reserve(theta, R0), self.cert_cost(theta), float('inf')
        return best

    def cert_cost(self, theta):
        return theta.alpha_cost + theta.seam_samples * theta.per_seam_cost

    ctx.ccl.observe(ctx.last_node, ctx.last_cost_pred, measure_cost(obs, tau_cmd))
    ctx.ccl.rho_cost -= measure_cost(obs, tau_cmd) * ctx.dt
    ctx.brc.h_min = ctx.cca.R.required_reserve(theta, ctx.R0)   # 随漂移更新

    return C, spatial_cert, claims, metrics, rewards

## 2. 推导

**引理 143（资源准入是纯过滤器 / 安全地板不变）** 设 v18 在 v17 之上只做四件事：BCA 追加合取约束、PBS 在准入集内选择、SRA 触发 v16 认证的恢复动作、CCA 只在 `Θ_safe` 内换认证参数。则对任意输入分布（含对抗输入），`Exec_v18 ⊆ Exec_v16`；相对固定参数 v17，BCA/PBS/SRA 只减不增。若 CCA 放宽 θ，则 `Exec_v18 ⊆ ⋃_{θ∈Θ_safe} Exec_v17(θ) ⊆ Exec_v16`——放宽只提升活性，不越过 v16 锚集。证明：BCA 的各因子均为合取谓词（`PC ∧ BRC ∧ CCL ∧ Solv`），只会缩小候选集；PBS 是选择函数，返回值必属于其输入集；SRA 的恢复动作取自 v16 认证锚；CCA 的 θ 取值域为 `Θ_safe`，而由引理 137 对每个 θ∈Θ_safe 都有 `Exec_v17(θ)⊆Exec_v16`。故不存在任何通道新增节点或放宽 v16 锚集。∎ 推论：**资源层的失效模式仍是单向的——活动性下降；v16 安全地板不降。**

**引理 144（偿付不变集的生存性）** 定义 `K = {x : h_bal(x) ≥ h_min + h_recover ∧ ρ_cost(x) ≥ c_need}`。若 BRC 要求计划终态 `h_bal ≥ h_min + h_recover`、CCL 要求计划后 `ρ_cost ≥ c_need`，且 SRA 的恢复动作在 K 上满足 CBF 条件且成本上界 `≤ c_need`，则 K 在 v18 策略下前向不变：机器人永不进入"无法负担安全停机"的状态。证明：对计划 epoch 归纳。初始若 x∈K，BCA 的 `Solv` 因子保证执行任意被准入的计划后仍∈K（终态储备与成本均满足 K 的门槛）；若 x∉K，SRA 立即中断并执行恢复，恢复动作的 CBF 条件把状态拉回 `h_bal ≥ h_min`、成本上界保证 `ρ_cost ≥ 0`，再经一次回补进入 K。恢复动作本身由 v16 认证锚给出，故不引入新风险。∎ 推论：**"安全停机"是永远可负担的最后一份资产——这是成本控制中的流动性底线。**

**引理 145（计算-储备互换与最优认证强度）** 设安全水平 `R(θ, h_min)` 关于认证强度 θ 单调不增、关于物理储备 `h_min` 单调不增且连续，则对任意目标 `R0`，等安全集 `L(R0)={(θ,h_min):R=R0}` 是一条下降曲线，沿其有互换汇率 `exch(θ,h_min) = dh_min/dc_cert = -(∂R/∂c_cert)/(∂R/∂h_min) < 0`。CCA 选 `L(R0)` 上 `c_cert(θ)·p_c + h_min·p_r` 的最小点，即在固定安全水平下经济代价最优，且该点 θ∈Θ_safe（引理 143 仍成立）。证明：由隐函数定理，`R` 连续单调可微时等值线局部为曲线，斜率即 `-(R_θ θ')/(R_h)`；沿等值线目标值不变，最小化线性经济代价即为切点。θ 的约束域为 `Θ_safe`，故结论不越出安全族。∎ 推论：**没有"绝对更安全"的配置，只有"在同一安全水平下更便宜"的配置**——计算贵时买储备，储备贵时买计算。

**引理 146（平衡储备的耗散-回补与"过度保守反而不安全"）** 设储备动力学 `ρ_{t+1} = ρ_t + a(u_t) − d(w_t)`，a 为回补量（消耗成本），d 为扰动消耗，`d` 可被对手取任意非负序列。若策略 π_static 令 `a≡0`（只最大化即时 margin、永不回补），则存在扰动序列使 `ρ` 单调下降至 `< h_min`；若策略 π_repl 在 `ρ < h_min+ε` 时插入回补（SRA 规则），则存在成本预算使 `ρ` 有界且 `≥ h_min`。证明：取 `d_t` 使累计消耗超过初始 margin，π_static 下 `ρ→0`；π_repl 每次跌破阈值即回补 `a ≥ ε`，只要回补成本可负担（CCL 保证），`ρ` 被拉回阈值以上，形成有界不变带。∎ 推论：**平衡是预算管理而非 margin 最大化**——这是"平衡控制"对证书架构最反直觉的贡献，也解释了为何 v18 需要主动回补而非静态保守。

**引理 147（成本方差触发的储备加严）** 若 CCL 用预测-实际方差 σ² 加宽上界 `Ĉ = ĉ + κ(σ)·σ`，且方差超阈值时 κ 单调增大，则成本证书的保守度随模型失配单调上升；给定 σ 的校准，`Ĉ` 仍是真实成本的高概率上界。故模型漂移不会导致成本低估而"破产"，只会导致更多计划被判不可负担（活性下降）。证明：`Ĉ` 关于 σ 单调不减，κ 单调增大保证大失配时上界抬升更快；在 σ 为真实误差标准差的高概率上界假设下，`ĉ+κσ` 覆盖真实成本的概率 ≥ 1−δ。∎ 推论：**与 v17 同构——成本层失效只损活性不损安全**，代价是可能过度保守（由 CCA 的互换机制部分对冲）。

**引理 148（v18 失效退化链）** 六组件逐一失效的退化关系成立：BRC→固定静态余量（v17+固定安全余量）；CCL→成本视为 0 且只保留 `c_need`（v17，安全但可能超额执行）；BCA→放行 v17 准入集（v17）；SRA→每 epoch 末强制 safe-stop（v16 单步，更保守）；PBS→按 `V(π)` 最大者选（v17）；CCA→固定最保守 θ（v17 保守配置）。六者全失效 ⇒ v17，再沿 v17→v16→…→v6 退化链退回。证明：逐项检查各失效替换均不引入新授权、不改变 v16 锚集，且替换后的行为是原行为集合的子集或等价保守版。∎

## 6. 已知风险与失效模式

1. **"账面偿付、实际资不抵债"（最大风险）**：成本-to-go 与扰动消耗均为估计，新颖计划/模型失配/对抗扰动可使真实消耗远超上界，系统误判为偿付充足。缓解：方差加严、鲁棒扰动界、在线模型校准、硬性 `h_min` 与 `c_need` 缓冲、对抗审计。
2. **CBF 模型失配**：接触切换、摩擦变化、负载突变使 `h_bal` 证书失效。缓解：多 CBF 取 min、鲁棒 CBF、接触域分模型、保守 `h_min`。
3. **汇率标定错误**：错误地"少算多留"（过度保守、僵死）或"多算少留"（真实安全下降）。缓解：在线标定、保守初始汇率、汇率漂移监控、定期全认证抽检。
4. **成本不可比/不可加**：能量、热、算力量纲不同，简单加权可能掩盖关键约束。缓解：分层记账、硬约束优先（热/算力作为硬上限而非软加权）、Pareto 而非单一标量。
5. **多指标 min 的"记分卡掩盖"**：min 可能被一个始终很小的指标支配。缓解：按里程碑切换关键指标、指标分族、异常指标告警。
6. **回补动作本身的风险**：迈步回补可能摔倒。缓解：回补动作必须是 v16 认证锚、仅在 `K` 内触发、回补前先偿付检查。
7. **偿付约束过度保守导致僵死**：长期不动作、任务停滞。缓解：CCA 互换对冲、动态 `h_recover`、活性监视与告警。
8. **方差阈值抖动**：`τ_var` 附近反复加严/放松。缓解：迟滞、滑动窗方差、最小驻留时间。
9. **认证预算与实时调度竞争**：CCA 降 θ 省时，但 BRC/SRA 又占时。缓解：认证进程隔离、预算预分配、关键路径白名单。
10. **长期能量/热模型漂移**：电池老化、散热退化使成本上界失效。缓解：周期重标定、老化感知、保守折扣。
11. **与 v17 新鲜度阶梯交互**：计划越旧，执行成本与储备消耗可能变化。缓解：成本证书随 `τ` 重估、陈旧计划成本加严。
12. **多机/多计划共享预算**：共享能量/算力时公平性与死锁。缓解：预算分区、优先级与抢占、集中仲裁日志。

## 7. 本轮最大风险

**一句话**：储备证书与成本证书都建立在"未来消耗与成本-to-go 的上界估计"之上，而新颖计划、模型失配或对抗扰动可以让真实消耗远超估计，使系统在账面上偿付充足、实际储备已为负——即成本/平衡模型的外推误差把"偿付保证"悄悄变成了"虚假会计"。
