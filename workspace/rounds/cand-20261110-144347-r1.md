# 第 45 轮（承接第 44 轮 v21；本轮灵感：服务设计 × 人形机器人） · Service-Cert × Humanoid-Cert：把「服务旅程」升为证书的交付单元，把「人形具身」升为带期望校准的承诺（四层架构 v10）

> 承接第 44 轮 v21（Pose-Cert × Data-Cert）。v21 自陈最大风险是「审计集与采集策略不独立 → 覆盖自我确认（Goodhart）」。它把证书栈的根信任补到了姿态与数据，但它与 v9–v21 全体共享一个仍未言明的假设：**(H4) 证书的最小交付单元是「单个动作/片段」，且唯一一等失败是「不安全动作」；对「服务」只承担「不伤害」，不承担「守约、可恢复、可被正确信任」。** 一切结论都是「这一帧不撞、这一步可达、这一段安全」，而人形机器人是以**服务**交付的：一次服务是跨越多个触点、多个回合、多个参与者的**旅程**，带一个对外承诺（SLA / 服务保证）。两个灵感词正好命中 H4：**服务设计**迫使我们把「服务蓝图/旅程、前后台可见性、失败点、服务补救」升为一等对象，把「动作证书的合取」升级为**旅程级概率时序契约证书**；**人形机器人**迫使我们承认**具身本身就是一份承诺**——人形形态会让人预期「像人一样」的能力，而全身平衡/跌倒/扫掠/灵巧接触是轮式机械臂完全没有的新失败模式。二者耦合出本轮真正的新问题：**动作 sound 不等于服务守约——因为失败在触点间相关、恢复能救回失败、而 fail-closed 对「服务」本身就是违约；更危险的是拟人形态会让客户把安全责任让渡给机器人（过度信任），使下游证书在「认证能力之外」的交互里静默失效。**

## 0. 直觉与动机

**灵感 1（服务设计 → 证书单位从「动作」升为「服务旅程」，SLA 升为可证契约）**
直觉：不该只问「这一步安全吗」，而该问「这次服务旅程，以多大概率守约」。把服务蓝图 SB 做成一等公民：阶段/触点、前台/后台/支撑、可见性线、失败点 FP、恢复路径 R。服务契约是旅程上的概率时序逻辑公式 Φ_s（窗口内完成 ∧ 满意度 ≥ s ∧ 全程安全 ∧ 可用率 ≥ ρ），服务契约证书 SCC 保证 P(Φ_s) ≥ 1−α_s。关键洞察：**SCC 不是动作证书的简单合取**。朴素合取 Π(1−p_i) 会过度惩罚「可恢复的失败」；朴素析取又会不 sound。正确对象是**带恢复覆盖的可靠性框图（RBD）**：旅程失败概率 ≤ Σ_{未覆盖} p_i + Σ_{覆盖} p_i(1−q_i)（union 界永远 sound），块独立时用乘积界收紧。

**灵感 2（人形机器人 → 具身本身是承诺：全身/跌倒/扫掠 + 拟人期望校准）**
直觉：人形不是外观问题，形态本身在对外声明能力。两个新失败面必须证书化：(a) **全身具身证书**——跌倒概率、全身扫掠体（含手臂/工具/负载）、接触力、灵巧手，且全都以姿态证书 P_t 为条件（姿态一错，平衡与扫掠体同时失效）；(b) **期望校准证书**——人形拟人度 a 越高，客户默认能力 \hat C 越高，越容易过度信任（站进扫掠体、期待被接住、把监护责任让渡）。所以要保证「感知能力与认证能力之差有界」，且在高风险维度上强制 \hat C ≤ C_cert。

**灵感 3（耦合 → 安全-服务-信任的字典序，恢复证书取代裸 fail-closed）**
直觉：服务设计讲「关键时刻」与「服务补救悖论」——一次被优雅恢复的失败，信任可能不降反升；而人形机器人恰好有很强的社会存在感。于是目标不是单一「安全」，而是**字典序三目标**：安全（硬，最高优先，失败只能安全停机）> 服务守约（软，可降级/换手/兜底/补偿）> 拟人信任校准（体验）。失败处理因此分层：安全谓词失败 → 强制 fail-closed；服务谓词失败 → 触发**恢复证书**（降级服务、换人、人工兜底、补偿），且恢复动作自身必须被认证（恢复不得引入新风险）；信任偏差超界 → 前台校准。这样把 v21 的裸 fail-closed 升级为**分层失败阶梯**。

**耦合升级**：SCE（服务契约引擎）把蓝图/旅程编译成旅程级契约与 RBD 组合界；RCE（恢复证书引擎）产出分层失败阶梯与恢复证书；TCE（信任校准引擎）用「可见性非干扰」约束前台表达；WBE（全身证书引擎）把具身失败面接到姿态根租约上；SPE（服务组合引擎）防止「通用人形」的能力幻觉。四层架构由 v9 的「姿态根信任 + 数据治理」升级为 v10：在根信任层加上**具身**，在数据治理层之上加**服务层**，形成「服务契约 → 动作/几何/姿态/具身证书 → 失败点/恢复 → 前台承诺」的闭环。

## 1. 形式化定义（增量：定义 50–55）

**定义 50（服务蓝图与服务旅程）**
服务蓝图 SB = (S, E, L_vis, FP, R)：S 为阶段/触点集合（front / back / support 三类），E ⊆ S×S 为转移，L_vis 为**可见性线**（把后台动作对客户遮蔽的边界），FP 为失败点集合，R 为恢复路径集合。一次**服务旅程** j 是 SB 上一条路径，携带参与者 (客户 c, 机器人 r, 人工兜底 h) 与时间窗 [0,T]。旅程状态 y_t = (s_t, τ_t, b_t, H_t)：当前阶段、客户信任、已用资源预算、已发生失败历史。

**定义 51（服务契约证书与旅程级组合界）**
服务契约 Φ_s 是旅程上的概率时序逻辑公式（例：□[0,T] safety ∧ ◇[0,T] complete ∧ satisfaction ≥ s ∧ availability ≥ ρ）。**服务契约证书** SCC_j 满足 P(Φ_s(j)) ≥ 1−α_s。设失败点 fp_i 的条件失败概率 p_i，恢复覆盖 q_i（由定义 52 的恢复证书给出；未被覆盖则 q_i 记 0）。则**永远 sound 的 union 界**：
P(¬Φ_s) ≤ Σ_i p_i(1−q_i) + ε_dep + ε_shift；
若块/旅程独立，则用更紧的 RBD 乘积界 P(Φ_s) ≥ Π_i[1 − p_i(1−q_i)] − ε_dep − ε_shift。**关键命题**：动作全 sound ⟹ 旅程 sound **不成立**（存在恢复与依赖）；反之旅程 sound 也不推出每个动作都单独 sound（恢复可吸收个别失败）。因此 SCC 必须基于 RBD 而非合取，且必须显式区分「已枚举失败点」与「开世界未枚举失败点」。

**定义 52（分层失败阶梯与恢复证书）**
对失败 f，按字典序分层：tier(f) = safety 若 f 违反安全谓词；否则 service 若违反服务谓词；否则 trust。**恢复策略** ρ_rec 是从可达失败状态到「安全降级状态 / 人工兜底 / 补偿」的映射。**恢复证书** RC 保证：∀ 可达 f，ρ_rec 执行后以概率 ≥ 1−α_r 到达满足**降级契约** Φ_s^deg 的状态，且**恢复动作自身**满足安全谓词（不得引入新风险）；safety 层不允许「恢复后继续」，只能 fail-closed（安全停机是唯一合法恢复）。**恢复命题**：若 RC 成立，则定义 51 中的 q_i ≥ 1−α_r；未覆盖失败点 q_i=0，按 fail-closed 计入违约上界。字典序保证「恢复」永远不会以牺牲安全为代价换取服务。

**定义 53（拟人期望-信任校准与可见性非干扰）**
设拟人度 a∈[0,1]，客户感知能力 \hat C = f(a, σ_front, prior)，认证能力 C_cert。**期望校准证书** ATC 保证：| \hat C ⊖ C_cert | ≤ ε_trust，且 **∀ 高风险能力维度 dim（承重/避让/接物/近人）: \hat C_dim ≤ C_cert_dim**（禁止过度信任）。**可见性非干扰**：前台信号 σ_front 关于后台未认证状态 U_back 的条件互信息 I(σ_front; U_back | C_cert) ≤ ε_leak——前台只能表达「证书支撑得起的置信」，不能把后台原始不确定性伪装成确定。**信任动力学**（服务补救悖论）：τ_{t+1} = τ_t + A·1[success] − B·1[fail ∧ ¬recovered] + G·1[recovered]，G>0 允许「被恢复的失败提升信任」；ATC 同时约束信任轨迹不越界。

**定义 54（全身具身证书）**
人形引入新失败面。**全身证书** WBE = (Fall, Swept, Contact, Dex)，全部以姿态证书 P_t 为条件：P(fall within H | P_t) ≤ β；全身扫掠体（所有连杆 + 工具 + 负载）满足 □¬inside_person；接触力 ≤ f_max；灵巧手操作有独立的接触/滑移证书。**具身根命题**：姿态根租约过期或未观测层 → WBE 立即级联失效（姿态错误会同时破坏平衡判据与扫掠体），不得局部降级。

**定义 55（服务组合与迁移证书）**
人形是通用平台，同一具身要服务服务组合 {Φ_s^1..Φ_s^k}。**服务组合证书** SPC 保证切换/共享具身不破坏任一契约；**迁移命题**：若目标服务在源服务的 ε-邻域（能力/场景/接触模式），且用密度比加权 + 分块共形，则迁移覆盖 ≥ 1−α_s−ε_shift；超出邻域必须重新认证，禁止「通用人形能力幻觉」。

## 2. 新增产出与既有 IP 升级

### 2.1 IP-63 SERVICE-CONTRACT-ENGINE（服务契约引擎 SCE）
1. **服务蓝图建模**：阶段/触点/前后台/可见性线/失败点/恢复路径；蓝图即证书的装配图。
2. **旅程级契约编译**：把 SLA 编译为概率时序逻辑 Φ_s；区分安全（安全层）与服务（服务层）子公式。
3. **RBD 组合界**：从下层动作/几何/姿态/具身证书取 p_i，从恢复证书取 q_i，输出 union 界（永远 sound）与乘积界（独立时更紧），显式标注未枚举失败点。
4. **契约下推**：把旅程契约分解为对下层动作证书的要求（哪些触点必须多严），形成「服务→动作」的需求回推。

### 2.2 IP-64 RECOVERY-CERT-ENGINE（恢复证书引擎 RCE）
1. **分层失败阶梯**：safety→fail-closed；service→降级/换手/兜底/补偿；trust→前台校准。
2. **恢复证书**：证明恢复策略在所有可达失败状态都能到达安全降级态，且恢复动作本身安全。
3. **恢复动作认证**：恢复过程中执行的动作仍走 L1–L3 证书，禁止「恢复即豁免」。
4. **服务补救账本**：记录恢复成功/失败与信任变化，供 ATC 与 SPE 使用。

### 2.3 IP-65 TRUST-CALIBRATION-ENGINE（信任校准引擎 TCE）
1. **期望建模**：由拟人度、前台信号、用户先验估计 \hat C。
2. **校准证书**：|Δ_trust| ≤ ε_trust，高风险维度强制 \hat C ≤ C_cert。
3. **可见性非干扰**：前台表达只能由证书支撑的量导出；后台未认证不确定性不得越过可见性线。
4. **前台校准策略**：主动表达不确定性、请求确认、行为示范、必要时拒绝并解释。

### 2.4 IP-66 WHOLE-BODY-CERT-ENGINE（全身证书引擎 WBE）
1. **跌倒证书**：平衡判据 + 跌倒概率上界 + 安全跌倒（不压倒人、损伤 ≤ d_max）。
2. **全身扫掠体**：含手臂/工具/负载的 swept volume，□ 提升为「不含人」。
3. **接触/灵巧证书**：接触力、滑移、抓取稳定；与姿态证书联立。
4. **具身级联**：WBE 以 P_t 为条件，姿态根失效 → 全身证书失效。

### 2.5 IP-67 SERVICE-PORTFOLIO-ENGINE（服务组合引擎 SPE）
1. **能力-服务匹配**：把服务需求与认证能力对齐，超出即拒接。
2. **迁移证书**：ε-邻域内迁移、加权分块共形；越界强制重认证。
3. **组合冲突检测**：多服务共享具身时的资源/安全/契约冲突求解。
4. **反能力幻觉**：禁止用「人形通用」替代逐服务认证。

  IP-60 PSE: 姿态证书 P_t + 根租约

## 5. 本轮最大风险

**一句话**：服务契约证书的 sound 性依赖「服务蓝图失败点完备」这一在开放人机服务中不可验证的假设——真实失败点会从蓝图之外长出（社交误解、临时工具、非结构化环境、多人博弈），这些未枚举失败点既不在恢复覆盖里、也未必触发安全层 fail-closed，使旅程级 SLA 被系统性高估；同时前台可见性若被「表演式过度承诺」利用，会把真实能力边界藏回后台，形成服务层 Goodhart。因此 E103（失败点完备性/开世界反例）与 E107（可见性非干扰/过度信任）必须设为红线，默认回退到「安全字典序优先 + 未枚举失败点一律视为安全层 fail-closed + 高风险能力维度强制 \hat C ≤ C_cert」。

### IP-63 SCE：蓝图、旅程契约与 RBD 组合界
```
def build_blueprint(stages, edges, visibility_line, fail_points, recoveries):
    return Blueprint(stages, edges, L_vis=visibility_line,
                     FP=fail_points, R=recoveries)

def compile_contract(bp, window, satisfaction, availability):
    # 概率时序逻辑；显式区分安全层与服务层子公式
    return Phi_s = Always(window, safety) and Eventually(window, complete) \
                   and (satisfaction >= s) and (availability >= rho)

def fail_terms(journey, certs, recoveries, alpha_r):
    terms = []
    for fp in journey.fail_points:
        p = certified_fail_prob(fp, certs)      # 由下层动作/几何/姿态/具身证书下推
        rc = recoveries.get(fp)
        q = (1 - alpha_r) if (rc is not None and rc.valid()) else 0.0
        terms.append((fp, p, q))
    # 开世界：未枚举失败点显式建模为安全层最坏情形
    terms += [(u, P_MAX, 0.0) for u in journey.unenumerated_fail_points]
    return terms

def service_contract_cert(journey, certs, recoveries,
                          alpha_s, eps_dep, eps_shift, independent):
    terms = fail_terms(journey, certs, recoveries, alpha_r)
    if independent:
        viol = 1 - prod(1 - p*(1-q) for _, p, q in terms)   # RBD 乘积界
    else:
        viol = sum(p*(1-q) for _, p, q in terms)             # union 界，永远 sound
    uncovered = [(fp, p) for fp, p, q in terms if q == 0.0]
    assert viol + eps_dep + eps_shift <= alpha_s, "contract_not_provable"
    return SCC(phi=Phi_s, violation_upper=viol + eps_dep + eps_shift,
               uncovered=uncovered)

def pushdown_contract(phi_s, bp):
    # 服务→动作：把旅程级违约预算分解到各触点，得到下层证书门槛
    budget = alpha_s
    return {tp: allocate(budget, tp, phi_s) for tp in bp.touchpoints}
```

### IP-64 RCE：分层失败阶梯与恢复证书
```
def failure_tier(f, phi_s):
    if violates(f, phi_s.safety):  return 'safety'
    if violates(f, phi_s.service): return 'service'
    return 'trust'

def recovery_policy(f, bp):
    tier = failure_tier(f, bp.phi_s)
    if tier == 'safety':
        return FailClosed('safe_stop')                  # 字典序最高，不恢复
    if tier == 'service':
        return select([degrade_service, handoff_human, compensate],
                      key=recovery_cost, must=has_valid_RC)
    return FrontStageCalibrate(f)                        # 交给 TCE

def recovery_certificate(rho, reachable_failures, alpha_r, Phi_deg):
    for f in reachable_failures:
        assert rho(f).reaches_safe_degraded_state(f)     # 可达安全降级态
        assert action_cert_ok(rho(f))                    # 恢复动作自身通过证书
        assert satisfies(rho(f).target, Phi_deg)         # 降级契约
    return RC(success_prob=1-alpha_r, degraded_contract=Phi_deg)

def lexicographic_guard(phi_s, action_cert, rc, f):
    # 安全 > 服务 > 信任：绝不以服务恢复换安全
    if not action_cert.safe:     return FailClosed('safety_first')
    if not action_cert.service:  return (rc.apply(f) if rc.valid_for(f)
                                         else FailClosed('no_recovery'))
    return Continue
```

### IP-65 TCE：拟人信任校准与可见性非干扰

def perceived_capability(a_humanoid, front_signals, user_prior):
    return f_hat(a_humanoid, front_signals, user_prior)

def trust_calibration_cert(robot_cert, human, front_signals, eps_trust):
    C = robot_cert.capability
    C_hat = perceived_capability(human.a, front_signals, human.prior)
    for dim in HIGH_STAKES:                 # 承重/避让/接物/近人
        if C_hat[dim] > C[dim]:
            return Recalibrate(dim, action='expose_boundary')  # 强制暴露边界
    leak = cond_mutual_info(front_signals, robot_cert.backstage_uncertainty
                            | C)
    assert leak <= eps_leak                # 可见性非干扰
    return ATC(gap=norm(C_hat - C) <= eps_trust, leak=leak)

def trust_dynamics(tau, outcome, recovered):
    if outcome == 'success':                return tau + A
    if outcome == 'failure' and recovered:  return tau + G   # 服务补救悖论
    return tau - B

def frontstage_policy(cert, human_state):
    # 只暴露证书支撑得起的置信，不泄漏后台原始不确定性

| 恢复证书过保守 → 频繁停机、服务不可用 | 中-高 | 分级恢复阶梯；兜底；监控恢复成功率与误触发 |
| 多参与者契约求交为空 / 服务不公平 | 中-高 | E110；公平性约束；冲突时安全优先调度 |
| 信任动力学被操纵（社交工程）→ 信任漂移越界 | 中-高 | ATC 轨迹约束；ICV 对抗测试；异常信任增量告警 |

## 6. 本轮最大风险

**一句话**：服务契约证书的 sound 性依赖「服务蓝图失败点完备」这一在开放人机服务中不可验证的假设——真实失败点会从蓝图之外长出（社交误解、临时工具、非结构化环境、多人博弈），这些未枚举失败点既不在恢复覆盖里、也未必触发安全层 fail-closed，使旅程级 SLA 被系统性高估；同时前台可见性若被「表演式过度承诺」利用，会把真实能力边界藏回后台，形成服务层 Goodhart。因此 E103（失败点完备性/开世界反例）与 E107（可见性非干扰/过度信任）必须设为红线，默认回退到「安全字典序优先 + 未枚举失败点一律视为安全层 fail-closed + 高风险能力维度强制 \hat C ≤ C_cert」。
