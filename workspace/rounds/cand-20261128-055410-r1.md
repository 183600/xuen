### 第 6 轮灵感驱动研究记录

**灵感词**：动作分块、可扩展性

**继承关系**：第 5 轮 CADVS-v5（IP-493~496，Certified Generative Execution, CGE）把提议从离散规则升级为条件流匹配，把记忆升级为检索增强 + 固化闭环，把人因升级为情感调制，并证明证书不变性（提议无关）与调制单调性，执行集 Exec_CADVS-v5 ⊆ … ⊆ Exec_v29。v5 仍有三处结构性瓶颈：(a) **认证粒度太细**——七门与 VACK/BCK 仍按每步/每周期重复消费，昂贵评估没有摊销，R49/R54 只是缓解未根除；(b) **框架是「单机、短时域、无组合」**——长任务只能整段重新规划，无法由已验证片段拼装，成本随时域线性增长；(c) **证书不可复用**——每个相似上下文都从零认证，机队规模 N 下成本 O(N)，无法扩展。两个灵感词统一为主题「分块认证与可扩展组合」（Chunked Certified Execution & Scalable Composition, CCX），形成 CADVS-v6（IP-497~500）。本轮自律：**硬门仍为七门，不新增门**；动作分块只改「认证粒度与执行契约」，可扩展性只走「组合代数 + 可靠复用」两条非侵入路径；执行集嵌套升级为 Exec_CADVS-v6 ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29。

**直觉与动机**：

1. **动作分块 → 把「逐步认证」摊销成「分块认证 + 运行时守卫合同」**。人做长动作不是每毫秒重新决策，而是规划一小段（chunk）再开环执行，期间只监控「是否还按预期走」。v5 的认证是逐点谓词，天然可以沿时间摊销：一次性认证 H 步的轨迹段，签发**分块证书 κ_h = (段轨迹, 各门最小边际 m_i, 误差管 E, 撤销储备 ε_rev, 出处签名)**；在线只需 O(1) 守卫监视器 M(state) 检查跟踪误差是否越出误差管、当前边际是否跌破储备。只要误差在管内，开环段的每步门都成立（鲁棒管论证）；一旦越管，**在撤销延迟 Δ 内 fail-closed 撤销剩余分块并重规划**，用储备边际吸收 Δ 内的最坏漂移。这把认证成本从 O(T·C_gate) 降到 O((T/H)·C_admit + T·C_guard)，是「认证可扩展性」在时间轴上的第一层。

2. **可扩展性 → 证书代数（近似幺半群）+ 可靠复用，把短证书拼成长计划、把已验证证书安全地跨上下文/跨机队复用**。分块证书在**接口匹配**（前段末态 ⊆ 后段入口集、守卫交界重叠）下可时序组合 ∘，在交互项被显式证书覆盖时可并行组合 ⊗，构成近似幺半群；**定理 9（分块不变性）**说明在 guard 兼容的分割类内，认证结果与分块粒度无关——这把 v5 的「提议无关性」推广为「分割无关性」，使长时域规划可折叠短 chunk 而非整段搜索。空间维度上，为每张证书计算**鲁棒半径 r_κ = min_i (m_i − ε_rev,i)/L_i^ctx**（L_i^ctx 为门分对上下文嵌入的 Lipschitz 常数），仅当查询上下文落在锚点半径内才复用；关键红线：**复用只允许「从本地已复验锚点出发的星形复用」，禁止沿复用链传递**——因为半径不满足三角传递，链式复用会把局部可证的误差放大成全局错误（信任洗白）。

**关键洞见**：v5 回答「提议 = 任意生成器时，证书边界如何不变」；v6 回答「认证如何在时间（分块摊销）、结构（组合）、规模（复用/机队）三个维度可扩展，同时边界只紧不松」。七硬门 kc_evidence_forged_v5 记号原样复用；新增只有：分块证书 κ_h（含守卫与撤销储备）、组合算子 (∘, ⊗)、复用注册表与鲁棒半径 r_κ、守卫监视器 M。Exec_v6 = Exec_v5 ∩ {分块守卫成立} ∩ {复用半径内}，因多出守卫与鲁棒约束而只缩不涨。

**形式化目标（增量）**：
1. 分块证书：κ_h = (x_{0:H}, {m_i}_{i=1}^7, E, ε_rev, G, prov)，m_i = min_{t∈[0,H]} (s_i(x_t) − τ_i)。
2. 守卫合同：G = {state : e ∈ E ∧ margin_now ≥ ε_rev}；监视器 M 每步 O(1)；撤销延迟上界 Δ。
3. 组合代数：(κ1 ∘ κ2) 需 post(κ1) ⊆ pre(κ2) ∧ G1∩G2 ≠ ∅；幺元 I = 空段 + 全域守卫；结合律在 guard 稳定类内成立。
4. 可靠复用：r_κ = min_i (m_i − ε_rev,i)/L_i^ctx；复用条件 d(c,c') ≤ r_κ；**星形、非传递**。
5. 成本模型：C_step(H) = C_guard + (1−ρ)(C_admit + C_comp)/H；受 P_guard_viol(H) ≤ δ 约束，H* = max 可行 H。
6. 定理 9（分块不变性）、定理 10（守卫可靠性/撤销安全）、定理 11（复用可靠性/非传递）、定理 12（摊销与机队可扩展界）。
7. Exec_CADVS-v6 = {x ∈ Exec_v5 : 分块守卫 G 成立 ∧ 复用半径内 ∧ ∧_i kc_i(x,c;τ^5)=1} ⊆ Exec_CADVS-v5。

**本轮最大风险**：**组合与复用的信任传递放大**——单张被投毒或鲁棒半径被高估的证书，可经内容寻址证书库与分块组合被「洗白」进长时域/跨机队计划，使局部有界误差变成系统性安全违例；节点级 fail-closed 守卫只看得到本地管，看不到跨节点组合语义，星形复用与本地复验只能局部限损，无法给出全局保证。

## 2. 关键算法骨架

### IP-497 CAC：分块动作认证核（准入 10 Hz；守卫 1 kHz O(1)）

```python
@dataclass
class ChunkedActionCertificationKernel:
    """CAC：把 v5 的逐点证书摊销为分块证书 + 运行时守卫合同。
    定理 9/10：守卫内可靠、越管即撤销；分块只改粒度不改门谓词。"""
    H: int = 50                    # 分块步数（1 kHz ⇒ 50 ms）
    L_gate: np.ndarray = None      # 七门对跟踪误差的 Lipschitz 常数（离线标定）
    v_max: float = 0.0             # 最大漂移速率
    delta_rev: float = 0.002       # 撤销延迟上界 Δ（s）
    eps_max: float = 0.0           # 误差管半径 ε_max
    m_res: float = 0.0             # 安全余量

    def certify_chunk(self, x_seg, c, gamma) -> ChunkCertificate:
        """对候选段 x_seg[0:H] 一次性跑七门；沿段记录最小门边际。
        仅在 m_i ≥ ε_rev,i 时签发，否则整段拒绝（fail-closed）。"""
        margins = per_step_gate_margins(x_seg, c, gamma)      # (H, 7)
        m_min = margins.min(axis=0)
        eps_rev = self.L_gate * (self.eps_max + self.v_max * self.delta_rev) + self.m_res
        if (m_min < eps_rev).any():
            return ChunkCertificate(ok=False, reason='INSUFFICIENT_RESERVE')
        guard = TubeGuard(eps_max=self.eps_max, eps_rev=eps_rev)
        return ChunkCertificate(ok=True, seg=x_seg, margins=m_min,
                                guard=guard, eps_rev=eps_rev, prov=sign(x_seg, m_min))

    def monitor(self, state, kappa: ChunkCertificate) -> GuardStatus:
        """O(1) 守卫：跟踪误差是否越管、当前边际是否跌破储备。
        违约 ⇒ 立即撤销剩余 chunk，下一周期重规划（fail-closed）。"""
        if kappa.guard.contains(state) and kappa.margin_now(state) >= kappa.eps_rev:
            return GuardStatus.OK
        return GuardStatus.REVOKE
```

### IP-499 CRR：证书复用注册表（内容寻址；星形、非传递）

```python
@dataclass
class CertificateReuseRegistry:
    """CRR：内容寻址证书库 + 鲁棒半径 + 星形复用。
    定理 11：d(c,c') ≤ r_κ ⇒ 证书对 c' 可靠（保守但可证）；复用不可传递。"""
    store: dict                       # key=hash(κ) → (κ, c_anchor, r_κ, sig)
    L_ctx: np.ndarray = None          # 七门对上下文嵌入的 Lipschitz 常数

    def register(self, kappa: ChunkCertificate, c_anchor) -> None:
        # r_κ 由锚点处最小边际扣储备后除以 Lipschitz 常数得到
        r = float(np.min((kappa.margins - kappa.eps_rev) / self.L_ctx))
        self.store[hash(kappa)] = (kappa, c_anchor, max(r, 0.0), sign(kappa))

    def lookup(self, c_query) -> ChunkCertificate | None:
        """只从本地已复验锚点星形复用；绝不沿复用链传递（防信任洗白）。"""
        for kappa, c0, r, sig in self.store.values():
            if dist(c_query, c0) <= r and verify(sig) and self._local_precheck(kappa, c_query):
                return kappa            # 命中：摊销掉一次完整认证
        return None
```

### IP-500 EFA-v6：复用 → 分块认证 → 组合 → 守卫执行

```python
@dataclass
class EvidenceForgingAssemblerV6:
    """EFA-v6：七硬门不变 + 分块认证 + 组合/复用；v5 作单分块退化路径。"""
    v5: EvidenceForgingAssemblerV5
    cac: ChunkedActionCertificationKernel
    cca: CertificateCompositionAlgebra
    crr: CertificateReuseRegistry

    def select_chunk(self, x0_state, t_now, rule_id, context) -> tuple[bool, ChunkCertificate | None, str]:
        # 第 1 层：复用命中 → 本地守卫预检 → 直接消费（摊销）
        kappa = self.crr.lookup(context)
        if kappa is not None:
            return True, kappa, 'REUSE_HIT'
        # 第 2 层：v5 提议（K 候选）→ CAC 分块认证（一次性跑七门）
        ok, x, tag = self.v5.select(x0_state, t_now, rule_id, context)
        if not ok:
            return False, None, tag
        kappa = self.cac.certify_chunk(x, context, gamma=context.gamma)
        if not kappa.ok:
            return False, None, 'CHUNK_REJECTED'
        self.crr.register(kappa, context)
        return True, kappa, 'CHUNK_FORGED'

    def plan_long_horizon(self, chunks: list[ChunkCertificate]) -> ChunkCertificate | None:
        """折叠短证书成长计划；任一接口不匹配则整条拒绝（fail-closed）。"""
        try:
            return reduce(self.cca.compose_seq, chunks, IDENTITY)
        except InterfaceMismatch:
            return None

    def run_control_loop(self, kappa: ChunkCertificate):
        for step in range(kappa.H):
            if self.cac.monitor(current_state(), kappa) is GuardStatus.REVOKE:
                return 'GUARD_REVOKE'        # fail-closed：中止剩余 chunk，下周期重规划
            execute(kappa.seg[step])
        return 'CHUNK_DONE'
```

## 3. 复杂度分析（增量更新）

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 | 实时性指标 |
|---|---|---|---|---|
| CAC.certify_chunk | O(H·\|gates\|) | O(H) 段缓存 | H=50 | 准入时域，一次摊 H 步 |
| CAC.monitor | O(1) | O(1) | — | < 0.01 ms/步 |
| CCA.compose_seq | O(1) 摊还（拼接 + 取交） | O(H_total) | 段数 m | 离线/准入 |
| CCA.compose_par | O(1) + 交互证书校验 | O(1) | 双臂/多机 | 离线 |
| CRR.lookup | O(log N) ANN（精确 O(N)） | O(N·\|κ\|) | N 证书数 | < 0.1 ms |
| CRR.register | O(log N) | O(\|κ\|) | — | 准入时域 |
| EFA-v6 控制环 | O(1)/步 | O(1) | H | **P99 ~0.45 ms（v5 0.55 ms）** |
| 每步认证均摊 | C_guard + (1−ρ)(C_admit+C_comp)/H | — | ρ, H | **较 v5 降 ~80%（H=50）** |

**成本模型与最优分块**：C_step(H) = C_guard + (1−ρ)(C_admit + C_comp)/H，关于 H 单调下降；但开环漂移使守卫违约概率随 H 上升，P_guard_viol(H) ≈ 1−(1−p)^H ≤ pH。故 **H\* = max{H : pH ≤ δ} ≈ δ/p**，在此约束下取最大 H 使摊销最优。分块收益条件：C_admit·p ≫ C_guard·δ，即昂贵认证 + 低漂移场景收益最大。

**机队可扩展性**：N 台机器、复用命中率 ρ 时总认证成本 ≈ N[C_guard + (1−ρ)(C_admit+C_comp)/H]；随任务重复度提高 ρ→1，成本相对 v5 的 O(N·C_admit) 显著次线性。**但复用只降低平均成本，不提升全局安全保证**（见风险 R63）。

**通信开销**：证书 = 段轨迹哈希 + 七门边际 + 守卫参数 + 签名，约 0.5~2 KB/张；机队分发增量 Δ 证书集，本地复验后才入库；原始轨迹不跨站传输，仅传证书与出处证明。

## 4. 正确性论证（增量更新）

### 引理 45（鲁棒管/守卫充分性）

**陈述**：设标称段门边际 m_i(t) = s_i(x_t) − τ_i，实际状态偏差 ‖e_t‖ ≤ ε_max，s_i 关于状态 L_i-Lipschitz。则实际门通过当且仅当 m_i(t) ≥ L_i‖e_t‖；若进一步 m_i(t) ≥ ε_rev,i = L_i(ε_max + v_max·Δ) + m_res，则在撤销延迟 Δ 内实际门始终通过且保有 m_res 余量。

**证明**：|s_i(x_t+ e) − s_i(x_t)| ≤ L_i‖e‖ ⇒ 实际分 ≥ s_i(x_t) − L_i‖e‖ = τ_i + m_i(t) − L_i‖e‖。误差在延迟内最坏增长到 ε_max + v_max·Δ，代入即得。∎

### 引理 46（复用半径的保守性）

**陈述**：若 d(c,c') ≤ r_κ = min_i (m_i − ε_rev,i)/L_i^ctx，则证书 κ 对上下文 c' 仍满足引理 45 的守卫充分条件；且该半径界一般不可加性传递。

**证明**：m_i(c') ≥ m_i(c) − L_i^ctx·d(c,c') ≥ ε_rev,i，逐门成立。非传递性：半径是「锚点到边界的距离」，d(c,c') ≤ r 与 d(c',c'') ≤ r 不能推出 d(c,c'') ≤ r（无三角约束），故链式复用可能越出真实验证域。∎

### 定理 9（分块不变性 / 分割无关性）

**陈述**：在 guard 兼容分割类 𝒫（每次细分保持 post/pre 接口与守卫交集非空）内，若组合满足结合律且门为逐点谓词，则认证结果与分块粒度无关：Exec^{𝒫1}_v6 = Exec^{𝒫2}_v6，对任意 𝒫1,𝒫2 ∈ 𝒫。

**证明**：门谓词逐点定义、不依赖分块；组合只重排同一组逐点约束的合取顺序（结合律），守卫取交与储备取 max 在 guard 稳定类内幂等，故合取集合不变。∎

**诚实边界**：不变性仅限 guard 兼容类；跨类（如整段 vs 子段）因开环误差管不同，整段认证可能更严，故 Exec_v6 ⊆ Exec_v5，且严格包含关系一般不成立为等式。

### 定理 10（守卫可靠性 / 撤销安全）

**陈述**：若传感器噪声与模型误差使守卫漏检概率 ≤ δ_mon，则分块开环执行期间发生未撤销门违例的概率 ≤ δ_mon + P(‖e‖ 越管且延迟内漂移 > m_res)。

**证明**：由引理 45，管内且边际 ≥ ε_rev 时无违例；违例只能发生在漏检或越管后延迟窗口，取并界。∎

### 定理 11（复用可靠性 / 非传递）

**陈述**：(i) 若 d(c,c') ≤ r_κ 且签名与本地复验通过，则 κ 对 c' 的每步门通过（可靠性）；(ii) 复用关系不传递，故 StarReuse 只允许锚点单跳。

**证明**：(i) 引理 46；(ii) 引理 46 非传递性反例。∎

### 定理 12（摊销与机队可扩展界）

**陈述**：在 P_guard_viol(H) ≤ δ 约束下，每步认证均摊成本 C_step ≤ C_guard + (1−ρ)(C_admit+C_comp)/H\*，H\* = max{H : pH ≤ δ}；N 机队总成本 ≤ N·C_step，且相对 v5 的 N·C_admit 之比 ≤ [C_guard + (1−ρ)(C_admit+C_comp)/H\*]/C_admit。当 ρ→1 或 H\* 大时比值 → 0。

**证明**：成本模型 + 定理 10 的违约约束，取可行域上界。∎

### 定理 v6（执行集四重收缩与分割不变性，总装）

**陈述**：在 v5 假设 (B1)~(B7) 及新增 (B8) Lipschitz 常数标定误差 ≤ ε_L 下：
(i) Exec_CADVS-v6 ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29（守卫/复用/储备均为额外合取约束）；
(ii) 分割不变性：guard 兼容类内认证与分块粒度无关（定理 9）；
(iii) 守卫安全：开环段违例概率由 δ_mon 与储备界（定理 10）；
(iv) 复用可靠但非传递（定理 11），仅星形单跳；
(v) 摊销与机队成本界（定理 12）；
(vi) 七锚完备性保持（v5 定理 8），分块/组合/复用均非新锚。

**证明**：(i) 额外合取只缩；(ii)(iii)(iv)(v) 分别由定理 9/10/11/12；(vi) 锚集不变。∎

**诚实声明**：(B8) Lipschitz 常数只能采样估计，低估 L 会使 r_κ 高估 ⇒ 假复用；跨个体/跨工况的 L 漂移无先验界；(ii) 组合正确性依赖接口契约完整，**并行组合的交互项极易遗漏**；(iii) 全局安全是局部守卫的合取，组合语义漏洞无法被节点级 fail-closed 捕获；(iv) 证书库的出处与版本一致性是新的信任根，签名密钥泄露即全局失效。

## 7. 本轮最大风险（最终确认）

**一句话**：**组合与复用的信任传递放大**——单张被投毒或鲁棒半径被高估的证书，可经内容寻址证书库与分块组合被「洗白」进长时域/跨机队计划，使局部有界误差变成系统性安全违例；节点级 fail-closed 守卫只看得到本地管，看不到跨节点组合语义，星形复用与本地复验只能局部限损，无法给出全局保证。
