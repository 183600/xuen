# 第 1 轮（新灵感循环；承接第 12 轮 CHUNK-SERVO）· WRIST-TRIAD：腕部相机不是“第二只眼睛”，而是“可主动测量的接触执行器”

> 检索/复核日期：**2026-11-02（UTC）**。赛事身份已再次核实：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新的灵感循环第 1 轮，三个随机词是「**腕部相机**」「**步态规划**」「**抓取规划**」。本轮不推倒第 12 轮 CHUNK-SERVO，而是修补它的三个盲点：**腕部内参假设错了、抓取目标没有显式定义、base/pivot 姿态通道基本没用**。新押注是 **WRIST-TRIAD**：用腕部相机做米制测量，用抓取规划决定“抓哪里”，用桌面姿态微步决定“从哪里够”，三者都是确定性控制器，VLA 仍是唯一学习模型。

## 0. 先把我这轮的思考路径摊开

我先把三个灵感词翻译成赛事里的可操作问题，而不是直接想“再加一个模块”：

1. **腕部相机**：挑战赛给四路 RGB，没有 depth；腕部相机离物体最近，但视野窄、会被夹爪挡、演示里没有手眼外参。上一轮我把它当“视觉伺服的眼睛”。这轮先问：它能不能当“测量仪”？如果内参已知，单目 + 已知桌面平面 + 机器人运动，就能在最后几厘米恢复米制尺度；如果内参未知，才需要标定。**先核实，不先假设。**
2. **抓取规划**：上一轮只做“把夹爪对齐到目标相对位姿”，默认抓取方式是给定的。但 32 个任务里大量失败可能不是“没对准”，而是“抓点选错/夹爪张不开/抓到了但滑”。所以这轮问：能不能在腕部图像里显式采样和评分抓取位姿，再把抓取位姿作为 VLA 规划的前置约束？
3. **步态规划**：桌面任务没有长距离行走，硬套“步态”会跑偏。但数据里 `lower_body` 有 12 个腿关节 + 3 个腰关节，`action.pivot` 有 `vx, vy, angle_z, pivot_3..5, height`，演示中高度从 0.608 m 到 0.740 m、yaw 到 ±0.8 rad、部分任务 base 的 `vx/vy` 命令超过 0.01（数据单位）。**所以“步态规划”在桌面任务里应降维成“支撑姿态/重心/工作空间微步规划”**：蹲一点、侧一点、转一点，让手够得到、腕部看得见、身体不摔。这不是导航，也不是 RL 步态。

然后我去核对事实，发现三件会改变方案的事：

- **纠错 1**：腕部相机其实有内参。`meta/info.json` 的 `wrist_left.color.camera_matrix` 和 `wrist_right.color.camera_matrix` 是完整的，左腕 `fx≈436.41, fy≈435.92, cx≈323.92, cy≈242.93`，右腕 `fx≈435.12, fy≈434.50, cx≈319.02, cy≈240.99`，还有 Brown-Conrady 畸变。上一轮 G0“腕部无内参、必须棋盘格标定”的前提不成立。**新的缺口不是内参，而是腕部相机到夹爪的手眼外参（hand-eye），以及跨机器人一致性。**
- **纠错 2**：`action.pivot` 不是摆设。32 个任务的演示统计里，**20/32** 任务 base 的 `vx/vy` 绝对值超过 0.01（数据单位，量级约 m/s），**18/32** 任务高度跨度 ≥5 cm，**22/32** 任务 yaw 跨度接近 1.6 rad。桌面任务的身体姿态是被演示实际使用的自由度，不是“全零回退”。
- **纠错 3**：主动腕部运动不能无脑喂给 VLA。Look Before You Act 的公开摘要报告：在 LIBERO 扰动起点下，给 π0.5 前面硬加相机重定位，成功率从 **46.3% 掉到 11.5%**；FoveaVLA 则用“外部相机的高分辨率 foveal crop”替代腕部相机，在 DROID 四个真实任务上把 π0.5 的 **52.1%** 提到 **77.1%**（单外部 RGB-D 为 70.8%）。两篇合起来的教训是：**主动视角有信息价值，但会制造初始观测分布偏移；要么用确定性控制器把主动运动限制在 VLA 之外，要么用主动起始状态的数据做对齐微调。** 本轮先选前者，成本低、合规风险低。

所以本轮的核心判断是：

> 榜首不到 30%，不只是“最后 3 厘米没有闭环”，而是**接触前的三个决策没有显式做**：从哪里看（腕部测量/遮挡）、抓哪里（抓取位姿/夹爪开口）、从哪里够（高度/腰/底座的支撑姿态）。CHUNK-SERVO 只解决了“看到偏了怎么修”，没有解决“看什么、抓什么、站哪里”。

一句话押注：

> **保留 30 步 VLA 规划 + 5 步执行块；在每个执行块前加一个确定性路由：需要测量就做腕部微步（LOOK），抓取不确定就重算抓取位姿（GRASP），目标够不到/被挡就调支撑姿态（STANCE）；三者都不触发时才做原来的视觉伺服（SERVO）。**

同时记录三条“不可用”证据（B 级，我们在公开 JSON 上复算）：

1. `leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`；8 个模型 ×32 任务的 `step_score ~ success_rate` 回归 **R² > 0.9999996，最大残差 <0.006**，每个模型一条不同斜率的直线（1.305–1.371）。这不是实测步骤分，是脚本生成的线性缩放。
2. 详情页 32 个任务视频仍全部是“测试视频占位，后续可替换为真实视频文件”（2026-11-02 抽查 MolmoAct2 与 WALL-OSS-0.5 的 Zip Up 详情页）。
3. 8 个模型的 32 维任务成功率两两平均 off-diagonal 相关系数仅 **0.0975**；256 个任务成功率里 **232 个**不是 10% 的整数倍，而每任务只有 10 次 trial。真实 10 次 trial 只能是 0/10、1/10、…、10/10。

**结论**：29.7% 只能当“赛事方预览上限/难度信号”。本轮不从榜单任务排名挖创新点；只从公开模型家族路线、官方规则/API/数据和近期论文挖。

### 1.2 腕部相机：内参是有的，缺的是手眼外参

HangCup 数据集 `meta/info.json`（2026-11-02 读取）给出：

```text
wrist_left.color.camera_matrix  = [436.4058, 0, 323.9217; 0, 435.9215, 242.9332; 0, 0, 1]
wrist_left.color.dist_coeffs    = [-0.05146, 0.05475, -0.0000356, 0.0001669, -0.01769]
wrist_right.color.camera_matrix = [435.1151, 0, 319.0249; 0, 434.4995, 240.9933; 0, 0, 1]
wrist_right.color.dist_coeffs   = [-0.05472, 0.05930, 0.0001395, 0.0004937, -0.01973]
```

头部双目则是 `fx≈282.37`、基线 **58.2526 mm**、`rectified: true`。换算一下：

- 头双目水平 FOV 约 **97°**，腕部约 **72.5°**；腕部是“近而窄”，头部是“远而宽”。
- 头双目 1 px 视差在 0.5 m 处约 **15 mm** 深度误差，在 1.0 m 处约 **61 mm**；这对“最后 2–3 mm 的插入”不够。
- 腕部在 5–10 cm 工作距离、2–4 cm 微步基线时，1 px 误差可压到 **1–2 mm 量级**（理想几何下），这才是接触段该用的尺子。

**方案变化**：G0 从“标定腕部内参”改为“验证内参跨机器人一致性 + 标定腕部到夹爪的手眼外参”。手眼外参可以从 G1 URDF/CAD 先验、演示中的已知 EE 运动、或 ActiveAlign-Waving 式的主动手部运动 + 可微渲染来估；没有手眼外参时，只用“桌面平面 + 腕部射线”做 2.5D，不硬做 6D。

### 1.3 `pivot` 与下身体：桌面任务的“步态”是支撑姿态，不是走路

32 个数据集的 `meta/stats.json`（2026-11-02 逐任务读取并聚合）显示 `action.pivot` 的 7 维名称是：

```text
vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height
```

聚合结果（B 级，逐任务 min/max 再取跨任务范围）：

| 维度 | 跨 32 任务范围 | 解读 |
|---|---:|---|
| `vx` | -0.333 – 0.439 m/s? | 部分任务有前后微调 |
| `vy` | -0.302 – 0.182 | 部分任务有左右微调 |
| `angle_z` | -0.800 – 0.800 rad | 底座 yaw 明显使用 |
| `pivot_3` | -0.516 – 0.569 | 语义未在 README 逐维定义，先不猜 |
| `pivot_4` | 0 – 0.627 | 同上 |
| `pivot_5` | 0 – 0 | 演示中恒零 |
| `height` | **0.608 – 0.740 m** | 13.2 cm 的蹲/站跨度 |

任务级统计：

- **20/32** 任务的 base `vx` 或 `vy` 绝对值超过 **0.01**（数据单位，量级约 m/s）；
- **18/32** 任务的 `height` 跨度 ≥ **5 cm**；
- **22/32** 任务的 `angle_z` 跨度 ≥ **0.79 rad**（接近 ±0.8）；
- 高度最低的任务包括 PickOutBatteries（0.608 m）、PaperCupStacking（0.626 m）、OrganizeTools（0.629 m）、OrganizeBookshelf（0.637 m）、PackPhone（0.637 m）、Unlock（0.640 m）、ZipUp（0.644 m）。

**结论**：桌面任务不是“底座焊死、只动双臂”。至少在这些任务里，演示者用高度/底座 yaw 去够远处、看近处、避遮挡。**“步态规划”在这里应实现为“离散支撑姿态库 + 平滑切换 + 稳定性检查”，而不是连续行走 RL。**

### 1.4 官方基座与接口：不变，但 `pivot` 是可用的第 21 维

- 官方 WLA：6B、约 2,500 h、64 任务、默认 `chunk_size=30 @30fps`、4 步扩散去噪；微调冻结 VLM，只训 DiT action head + robot-state projector，单张 24GB GPU。
- 挑战赛 API：四路 RGB 480×640；无 depth/camera_info/force/tactile；`action_chunk_size` 固定；chunk 内无新观测；`action.pivot[7]` 与双臂动作并列，属于 shared 动作；`reset()` 必须按端口隔离；N 个连续端口从 8765 起；单次 180 s。
- 数据：32 任务、**33,276 episodes / 169.28 h / 18,282,246 frames @30fps**；四路视频；头双目有内参/畸变/R/T/基线；腕部有 color 内参/畸变（本轮纠错）；`state_d435` 给头相机在 base 系的 6D 位姿；`lower_body[15]` = 12 腿 + 3 腰。

**接口含义**：`pivot` 是唯一能改变“身体高度/底座 yaw/腰/腿”的通道。把它固定为零，等于放弃一个演示里真实使用的自由度；但 `pivot_3..5` 语义未定义，必须先用单任务通道验证，不能猜符号。

### 1.5 头部方案的做法与瓶颈：都在“接触前决策”上留了空白

| 模型家族 | 公开路线 | 优势 | 与本轮相关的瓶颈 |
|---|---|---|---|
| **MolmoAct2** | Ai2 的 action reasoning model；Molmo 2-ER + action expert + adaptive depth reasoning；强调 3D 空间推理、推理加速、无 per-task 微调 | 3D/空间语义强；双臂 | 仍是开环 chunk；腕部只当输入，不主动测量；抓取位姿不显式 |
| **WALL-OSS-0.5** | X Square 4B VLA（3B VLM + action expert）；公开材料称 15 个真机任务 60.5% average task progress | 预训练可用；progress 高 | progress ≠ success，最后一步失败就 0 分；4B 实时性 |
| **DreamZero** | 14B Wan2.1 video-diffusion world-action model；预测未来视频再出动作 | 长程预测/规划 | 14B 推理重；世界模型不解决“现在偏 2 mm”；1 秒 chunk 更危险 |
| **π0.5** | Physical Intelligence 开放世界泛化 VLA | 语义/新场景泛化 | 接触密集任务精度；远程部署延迟；腕部视角固定 |
| **GigaBrain-0** | 世界模型生成数据 + VLA | 数据效率/泛化 | 生成数据物理保真度；最后接触 |
| **GR00T N1.5** | NVIDIA 通用人形 VLA | 生态/embodiment | 任务特定精度；抓取/插入细节 |

共同点：

- **都是 action chunk 开环执行**，chunk 内不看新图；
- **腕部相机是被动输入**，没有被当作“可主动运动的测量仪”；
- **抓取位姿没有被显式规划**，VLA 直接输出末端轨迹，夹爪开口和抓点只是隐变量；
- **身体姿态基本没被当成决策变量**，而演示里 height/yaw 明显变化；
- **世界模型解决“想象未来”，不解决“现在抓点错了/够不到/被挡住”**。

这就是 WRIST-TRIAD 的切入口：不去卷更大的 VLA，而是在 VLA 和接触之间加一个**确定性的接触前决策层**。

### 1.6 近期工作给出的三条边界

| 工作 | 公开结论 | 对本方案的约束 |
|---|---|---|
| **FoveaVLA**（arXiv 2610.20064，2026-10-14） | 用外部相机的高分辨率 foveal crop 替代腕部相机；π0.5 在 DROID 四个真实任务上 52.1% → 77.1%（Dual），单外部 RGB-D 70.8% | 腕部相机不是神圣的；但该工作需要 RGB-D/双目外部相机，挑战赛只有 RGB。我们应把腕部用于**测量/伺服**，不强行把它塞进 VLA 主输入 |
| **Look Before You Act**（arXiv 2610.23378，2026-10-16） | 在 LIBERO 扰动起点下，给 π0.5 前硬加相机重定位，成功率 46.3% → 11.5%；用主动终止状态做数据对齐后，40 任务 70.7%/72.7% | **主动腕部运动会造成初始观测分布偏移**；不让 VLA 直接吃“刚运动完”的图，或用主动起始数据微调 |
| **ActiveAlign**（arXiv 2610.36859，2026-10-27） | ActiveAlign-Waving 用主动手部运动 + 可微渲染做手眼标定；在真实 Unitree G1 上实现按钮/滑块毫米级操作 | 手眼外参可以用主动运动估；这正好补上腕部相机缺的外参，且是 G1 实证 |
| **GraspLDP**（arXiv 2602.22862，2026-02-26） | 把 grasp pose prior 注入扩散策略，并用腕部图像反投影做自监督 graspness | 抓取先验有效；但它是学习模型。我们优先用确定性几何 + 演示检索，避免单模型合规风险 |
| **STRIDER**（arXiv 2609.23483，2026-09-20） | 人形多步态分层 loco-manipulation，脚步/姿态/上肢协同 | 步态规划有价值；但桌面任务不需要连续行走，降维成支撑姿态更稳 |

**设计原则**：主动视角要用，但不能让 VLA “惊讶”；抓取先验要用，但不能变成第二个学习模型；步态要用，但不能变成连续行走 RL。

## 2. 诊断：CHUNK-SERVO 只修了“手抖”，没修“看错/抓错/够不到”

把一次接触失败拆成四个问题：

```text
Q1 看哪里？  腕部视野窄、夹爪遮挡、目标反光；固定视角可能根本看不到抓点
Q2 抓哪里？  夹爪开口/抓取轴/接近方向选错；对齐得再准也会滑/夹空
Q3 从哪里够？目标太远/太低/被挡；手臂接近奇异或关节限位；身体高度/yaw 没调
Q4 怎么修？  真正对齐误差；CHUNK-SERVO 的 5 步视觉伺服
```

上一轮把 Q4 做深了，但 Q1–Q3 仍是隐变量。于是出现一种“伺服很努力，但抓取点本身错了”的失败：视觉伺服把夹爪精确地对到一个不该抓的位置，成功率当然不涨。

本轮的顺序反过来：

```text
先决定“站哪里/看哪里/抓哪里”，再决定“怎么对准”。
STANCE → LOOK → GRASP → SERVO → CONTACT → RECOVER
```

不是每个任务都走全流程；路由根据置信度和残差跳过。

## 3. WRIST-TRIAD：三个确定性支点 + 一个路由

### 3.1 总架构

```text
                    ┌─────────────────────────────────────┐
                    │ Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ obs / action chunk
                                   ▼
        ┌──────────────────────────────────────────────────────┐
        │ Per-port Executive (CPU, deterministic)              │
        │  ├─ MODE ROUTER: LOOK / GRASP / STANCE / SERVO       │
        │  ├─ WRIST-METRIC: 内参 + 平面/双目/微步三角化         │
        │  ├─ GRASP-AFFORDANCE: 2.5D 对跖抓取采样/评分          │
        │  ├─ POSTURE-GAIT: 演示姿态库 + IK/稳定域              │
        │  ├─ CHUNK-SERVO: 5 步 IBVS/PBVS 修正                  │
        │  └─ action adapter: WLA 54D → API 21D                 │
        └──────────────┬───────────────────────────────────────┘
                       │ async, batched, per-port state
                       ▼
        ┌──────────────────────────────────────────────────────┐
        │ Shared VLA server (GPU): UnifoLM-WLA-1.0, 30-step     │
        └──────────────────────────────────────────────────────┘
```

- **唯一学习模型**：VLA（WLA 微调 action head）。
- **三个确定性支点**：腕部测量、抓取评分、姿态选择；无学习权重。
- **一个路由**：根据残差/置信度决定本执行块用哪个支点；避免“每个任务一个策略”。
- **保留**：5 步 chunk、相对目标、演示检索、数字孪生只做风洞、单任务通道 A/B。

### 3.2 WRIST-METRIC：用腕部相机做米制测量

三种由粗到细的测量模式，按可用性回退：

1. **桌面平面模式（默认，最稳）**：桌面高度在 episode 开始时用头双目/机器人运动标定一次；腕部像素射线与桌面平面求交，得到目标在腕部系/基座系的 3D 点。适合桌上的刚体、杯子、盒子、网口。
2. **头双目模式**：目标在头双目视野内时，用校正后的双目视差给 5–15 mm 级深度，作为腕部测量的先验/交叉验证。
3. **腕部微步三角化模式（LOOK）**：当目标反光/透明/被夹爪挡，或需要 <5 mm 深度时，让腕部做 2–4 cm、5–10° 的微小“观察步”，用 3 帧已知 EE 位姿和腕部内参做三角化；只在这个小窗口内使用，不把运动后的图直接喂给 VLA。

关键公式（腕部系 W、基座系 B、夹爪系 E）：

```text
像素 p = (u,v,1)
归一化射线 x_w = K_w^{-1} p
桌面模式：X_w = ray ∩ plane(table)
双目/微步：X_w = triangulate(p_1, p_2, T_1, T_2, K_w)
到基座：X_b = T_bE · T_EW · X_w
```

其中 `T_EW` 是腕部相机到夹爪的手眼外参（待标定），`T_bE` 来自 `*_ee_pose_gripper_base`。若 `T_EW` 不可信，只用“相对深度/桌面交点”驱动 2D 伺服，不输出绝对 6D 抓取。

### 3.3 GRASP-AFFORDANCE：先选抓点，再谈对准

在腕部图像里做 2.5D 对跖抓取采样：

```text
1. 目标 ROI：语言/头双目/颜色/深度边缘；无法分割时回退 VLA
2. 轮廓采样：边界点 + 局部法向
3. 对跖候选：一对边界点 (i,j)，宽度 w=|X_i-X_j|，中心 c，抓取轴 a
4. 评分：
   S = w1·对跖对齐 + w2·(1-|w-g|/g) + w3·接近净空
       + w4·腕部关节裕度 + w5·演示先验 - w6·碰撞/遮挡
5. 选 top-k，做短程 IK/碰撞检查；失败则降级为 VLA 原动作
```

为什么不是“6D 物体位姿网络”：透明杯、反光网口、变形毛巾的 6D 位姿不可靠；对跖抓取只需要局部轮廓、夹爪宽度和接近方向，容错更高。演示先验可以从 33k 成功 episode 的“夹爪闭合前 1–3 帧”统计，不训练新模型。

### 3.4 POSTURE-GAIT：桌面任务的“步态”是离散支撑姿态

把**可命令的** `action.pivot[7]` 统一成“姿态”；`lower_body[15]` 只作观测/验证，不直接下发：

```text
stance s = (height, base_yaw, base_x, base_y, waist_yaw, waist_roll, waist_pitch)
```

离线从 32 任务演示中提取每个任务的姿态分布，聚成 12–18 个离散 stance（3 个高度 × 3 个 yaw × 2 个腰前倾）。在线选择：

```text
s* = argmax_s [ reachability(target; s) + visibility(wrist/head; s)
                - stability_penalty(s) - transition_cost(s, s_current) ]
```

- `reachability`：G1 URDF + IK，检查目标是否在双臂舒适工作空间、是否接近关节限位/奇异。
- `visibility`：腕部/头部视锥 + 桌面遮挡的粗几何；不训练视觉模型。
- `stability`：支撑多边形/CoM 粗检查；桌面任务不做动态步态。
- `transition`：0.5–1.0 s 平滑插值；一次 episode 最多换 1–2 次 stance，避免抖动。
- 安全：先只动 `height` 与 `waist`，`base vx/vy` 默认零；单任务通道验证 `pivot_3..5` 语义后再启用平移。

### 3.5 MODE ROUTER：每个 5 步块只做一个决定

```text
if scene_moved and not explained_by_robot:
    RECOVER
elif target_out_of_workspace or arm_near_limit or wrist_occluded:
    STANCE (or LOOK if only occlusion)
elif grasp_quality < θ_g or gripper_width_incompatible:
    GRASP
elif servo_error > θ_e and target_visible:
    SERVO
else:
    MOVE (VLA feed-forward)
```

每个块最多 1 个支点，执行 5 步后重新观测；避免“同时调姿态、抓取、伺服”导致不可解释的耦合。路由阈值用仿真 + 单任务通道标定，不靠拍脑袋。

### 6.2 A/B 设计

- 每个任务 5–10 次，配对初始条件；
- 四个版本：`VLA baseline` / `+SERVO` / `+GRASP` / `+STANCE` / `+ROUTER`；
- 指标：成功率、步骤分、耗时、p99 延迟、恢复次数、碰撞/超时；
- 通过：至少 2/4 任务 +10pp，ZipUp 不回归 >5pp；否则不烧正式提交；
- 统计：配对差值 + bootstrap 95% CI；5 次只能看方向，不能宣称显著。

### 6.3 收益算术（设计目标，不是承诺）

- 若 4 个代表任务各 +10pp，只说明机制有效，不代表全局；全局要扩到 10–19 个任务；
- 若 10 个接触任务各 +10pp：`10/32×10 = +3.1pp`；
- 若 19 个 A 档各 +8pp：`19/32×8 = +4.75pp`；
- 人为干扰轴 +10pp：`0.2×10 = +2pp`；
- 姿态/抓取若只对 8 个任务有效：`8/32×10 = +2.5pp`；
- 保守合计 **+3–6pp**，乐观 **+7–9pp**；必须用配对 A/B 证明，不能把设计目标当结果。

### 6.4 提交节奏

1. **W0**：WLA + API adapter + baseline；单任务通道跑通 1 个任务；确认 `pivot` 语义/token/延迟。
2. **W1**：WRIST-METRIC 离线回放 + 手眼标定；不提交。
3. **W2–W3**：GRASP + STANCE 仿真/回放；4 任务 A/B。
4. **W4**：ROUTER 集成；p99/超时/端口隔离干跑。
5. **W5**：若允许多次提交，先交安全基线锁 tie-break，再交 WRIST-TRIAD；若只允许一次，等 4 任务过门再交。

## 7. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 手眼外参错 | 腕部 3D 偏 1–2 cm | URDF 先验 + 主动标定 + 重投影门；误差大只用 2D/桌面平面 |
| 腕部微步造成 VLA 分布偏移 | 成功率反降 | 微步只用于确定性测量；VLA 输入保持 canonical；I6 才做微调 |
| 抓取分割错 | 抓空/碰撞 | 只对刚体/清晰轮廓启用；低置信回退 VLA；夹爪宽度硬约束 |
| 姿态切换超时/失稳 | 180 s 预算/安全 | 先只调 height/waist；限速/限幅；一次 episode ≤2 次切换；base 平移默认关 |
| `pivot_3..5` 语义未知 | 动作异常 | 先返回零；单任务通道逐维验证；不猜符号 |
| 单模型解释 | 被判第二个模型 | 三个支点均无学习权重；I2 用几何评分，不用第二个网络；提交材料写清 C1/C2/C3 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |
| 榜单是预览 | 误判难度 | 不把榜单任务排名当实测；只用它当上限信号 |
| 透明/反光/变形 | 测量/抓取失败 | 只对刚体启用；腕部 2D + 桌面平面兜底；ZipUp 只做回归 |

## 8. 一句话押注

**把腕部相机从“被动输入”升级成“米制测量仪”，把抓取位姿和桌面支撑姿态变成两个显式决策，再用一个确定性路由器决定当前 5 步该看/该抓/该站/该修——在不新增学习模型的前提下，先修接触前的“看错、抓错、够不到”，再修接触中的“偏 2 mm”。**

**对方案的约束**：WRIST-TRIAD 必须每端口独立、CPU 轻量、不抢 GPU；VLA 是唯一学习模型；三个支点是控制器/几何算法，不是第二个策略。

| 相机 | 水平 FOV | 垂直 FOV | 0.5 m 处 1 px 视差深度误差 | 1.0 m 处 |
|---|---:|---:|---:|---:|

- **头双目适合 5–15 mm 级粗深度/防撞，不适合最后 2–3 mm 插入。**
- **腕部内参已知，适合 2D 像素→射线、桌面平面交点、近距离三角化；缺的是手眼外参 `T_EW`。**
- 上一轮 G0“腕部无内参、必须棋盘格标定”应撤销；新的 G0 是“跨机器人内参一致性 + 手眼外参”。

## 2. 问题形式化

### 2.1 坐标与手眼

定义：

- `B`：机器人 base 系（x 前、y 左、z 上）。
- `E`：夹爪/EE 系；`W`：腕部相机系；`T`：目标/受器系。
- `T_BE`：EE 在 base 系的位姿，来自 `*_ee_pose_gripper_base`。
- `T_EW`：腕部相机到 EE 的手眼外参（待标定/验证）。
- `T_WT`：目标在腕部系的位姿（由测量得到）。

则目标在 base 系：

```math
T_{BT} = T_{BE}\,T_{EW}\,T_{WT}.
```

若只看位置：

```math
X_B = T_{BE}\,T_{EW}\,X_W.
```

手眼标定目标：

```math
\min_{T_{EW}}\sum_i \left\|\pi\!\left(K_w,\;T_{EW}^{-1}T_{BE,i}^{-1}X_{B,i}\right)-p_i\right\|^2,
```

其中 `X_{B,i}` 可由桌面平面/头双目给出，`p_i` 是腕部图像点。没有已知 `X_B` 时，用 `AX=XB` 或 ActiveAlign-Waving 式主动运动。

### 2.2 腕部测量的三种模式与误差

#### 模式 A：桌面平面求交（默认）

桌面平面在 base 系：

```math
n^\top X_B = d.
```

腕部像素 `p=(u,v,1)` 的射线在腕部系：

```math
r_W = \frac{K_w^{-1}p}{\|K_w^{-1}p\|},\qquad o_W=0.
```

转到 base：

```math
o_B = T_{BE}T_{EW}o_W,\qquad r_B = R_{BE}R_{EW}r_W.
```

交点：

```math
\lambda = \frac{d-n^\top o_B}{n^\top r_B},\qquad X_B = o_B+\lambda r_B.
```

误差主要来自：像素定位、桌面高度 `d`、手眼外参、平面法向。桌面上 1 px 在 0.1 m 处约 0.23 mm 横向；若射线与平面夹角 30°，深度方向误差约 0.46 mm/px。**这是最后 2–3 mm 最便宜的量法。**

#### 模式 B：头双目

```math
Z = \frac{f\,b}{d_{\mathrm{disp}}},\qquad
\sigma_Z \approx \frac{Z^2}{f\,b}\sigma_d.
```

`f≈282.37`、`b=0.05825 m`：

| Z | 1 px 视差误差 |
|---:|---:|
| 0.5 m | 15.2 mm |
| 0.8 m | 38.9 mm |
| 1.0 m | 61.0 mm |

用途：粗深度、桌面高度、遮挡判断、腕部测量的交叉验证；不单独承担最后插入。

#### 模式 C：腕部微步三角化（LOOK）

腕部在 2–4 cm 横向基线上取 3 帧，已知 EE 位姿 `T_{BE,1..3}`：

```math
X_W = \operatorname{triangulate}(p_1,p_2,p_3,\;T_{EW}^{-1}T_{BE,i}^{-1}T_{BE,1}T_{EW}).
```

近似误差：

```math
\sigma_Z \approx \frac{Z^2}{f\,b_{\perp}}\sigma_p,
```

`b_{\perp}` 是垂直于视线的有效基线。`Z=0.1 m, f=436, b=0.03 m, σ_p=1 px` → 约 **0.76 mm**；`Z=0.15 m` → 约 **1.72 mm**。要求：

- 基线不能沿光轴（深度不可观测）；用横向/斜向微步；
- 运动前后要有静止帧，避免运动模糊；
- 微步只用于测量，不把运动后的图直接喂 VLA；
- 失败/超时回退桌面平面。

### 2.3 抓取规划的形式化

对腕部 ROI 的边界点 `X_i`、法向 `n_i`，采样对跖候选：

```math
w_{ij}=\|X_i-X_j\|,\quad
c_{ij}=\frac{X_i+X_j}{2},\quad
a_{ij}=\frac{X_j-X_i}{\|X_j-X_i\|}.
```

评分：

```math
S_{ij}=w_1 A_{ij}+w_2 W_{ij}+w_3 C_{ij}+w_4 M_{ij}+w_5 P_{ij}-w_6 K_{ij},
```

其中：

- `A_{ij}`：对跖对齐，`0.5(|n_i^\top a|+|n_j^\top a|)`；
- `W_{ij}`：宽度匹配，`exp(-((w_{ij}-g^*)/\sigma_w)^2)`，`g^*` 是理想开口（夹爪最大开口的 60–80% 或物体宽度先验）；
- `C_{ij}`：接近净空（夹爪体积到其他点的最小距离）；
- `M_{ij}`：IK 关节裕度/可操作度；
- `P_{ij}`：演示先验（抓点相对物体质心、接近角、闭合前夹爪开口）；
- `K_{ij}`：碰撞/遮挡惩罚。

输出 top-k 抓取位姿，经短程 IK/碰撞检查后，作为 VLA 末端轨迹的**前置约束**：VLA 仍负责“去抓”的粗轨迹，抓取位姿负责“抓哪里/什么方向/开口多大”。

### 2.4 支撑姿态的形式化

可命令的只有 `pivot[7]`。先只用语义明确的：

```math
s=(h,\psi,v_x,v_y),
```

`h=height`、`\psi=angle_z`、`v_x,v_y=base` 平移；`pivot_3..5` 先置零。

离线从 32 任务演示统计每个任务的 `s` 分布，聚成 12–18 个离散 stance。在线：

```math
s^*=\arg\max_s \left[
R(s)+\lambda_v V(s)+\lambda_b B(s)-\lambda_c C(s,s_0)
\right],
```

- `R(s)`：双臂 IK 可达性/可操作度（目标点能否舒适到达，是否接近关节限位/奇异）；
- `V(s)`：目标在腕部/头部视锥内的可见比例（粗几何/遮挡）；
- `B(s)`：支撑多边形/CoM 稳定裕度；
- `C(s,s_0)`：从当前姿态切换的时间/位移代价；
- 约束：`h∈[0.62,0.74]`、`|\psi|≤0.8`、`v_x,v_y` 默认 0，单任务通道验证后再开。

### 2.5 路由的形式化

每个 5 步块，给定：

- `e_t`：伺服残差（6D）；
- `q_t`：抓取评分（最高 `S` 或 top-k 一致性）；
- `R_t`：目标可达性；
- `v_t`：腕部/头部可见性；
- `m_t`：场景运动残差（第 11 轮 GEO-RESIDUAL 的 `edit_score`）。

路由：

```text
if m_t > θ_m:                         RECOVER
elif R_t < θ_R or arm_margin < θ_A:    STANCE
elif v_t < θ_v:                        LOOK
elif q_t < θ_q or width_bad:           GRASP
elif ||e_t|| > θ_e:                    SERVO
else:                                  MOVE
```

每个块只选一个支点；执行 5 步后重新观测。阈值用仿真 + 单任务通道标定，并加滞回（连续 2 帧才切换），避免抖动。

### 2.6 时间模型

设：

- `f_c`：evaluator 控制频率（假设 30Hz）；
- `H_c`：`action_chunk_size`；
- `τ`：网络 RTT + 推理 + 图像传输的等效延迟。

反馈周期：

```math
T_{\mathrm{fb}} \approx \frac{H_c}{f_c}+\tau.
```

| 场景 | `H_c` | `f_c` | `τ` | `T_fb` | 评价 |
|---|---:|---:|---:|---:|---|
| 官方 WLA 默认 | 30 | 30 | 50ms | **1050ms** | 接触段基本开环 |
| 本方案保守 | 5 | 30 | 50ms | **217ms** | 可做 1–2 次接触修正 |
| 本方案高延迟 | 5 | 30 | 150ms | **317ms** | 增益降档 |
| 低控制频率 | 5 | 10 | 50ms | **550ms** | 改 `H_c=3` 或只做 PBVS |
| 微步 LOOK | 3 帧+settle | 30 | 50ms | **~250ms** | 只用于低置信测量，最多 2 次/任务 |

姿态切换是慢时间尺度：0.5–1.0 s，一次 episode 最多 1–2 次；不进入 5 步快环。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port Executive (CPU)           │
                    │  ├─ MODE ROUTER                     │
                    │  ├─ WRIST-METRIC                    │
                    │  ├─ GRASP-AFFORDANCE                │
                    │  ├─ POSTURE-GAIT                    │
                    │  ├─ CHUNK-SERVO                     │
                    │  └─ action adapter                  │
                    └──────────────┬──────────────────────┘
                                   │ async, batched, per-port state
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared VLA server (GPU)            │
                    │  UnifoLM-WLA-1.0 / VLA-0, 30-step   │
                    └─────────────────────────────────────┘
```

- 每个端口一个 `Executive` 实例，独立 `reset()`、独立 plan cache、独立 stance/grasp 状态。
- 三个支点是 CPU 线程，不阻塞 websocket；VLA 请求异步、可批处理。
- 共享 VLA server 用 session ID 区分端口；模型权重只有一份，不违反单模型。
- GPU 6B bf16 约 12GB；一张 24GB GPU 可服务多个端口，具体并发取决于 batch/序列长度。

### 3.2 接口契约

提交 metadata 示例：

        "observation.images.cam_left_high":  [240, 320],

- 语言方面，WLA server 用 `unnorm_key`/固定 prompt，不直接吃挑战赛 `observation.language`；需要把 32 任务语言映射到 WLA 任务 key（或空 prompt），并在单任务通道验证。

动作返回（`ee` 模式）：

```python
{
    "meta.token": token,
    "action.left_gripper":  np.float32 (5,1),
    "action.right_gripper": np.float32 (5,1),
    "action.pivot":         np.float32 (5,7),
    "action.left_ee_pose_gripper_base":  np.float32 (5,6),  # absolute xyz+rpy
    "action.right_ee_pose_gripper_base": np.float32 (5,6),  # absolute xyz+rpy
}
```

注意：挑战赛 API 的 EE 动作是**绝对目标位姿**；WLA 输出的是**相对当前 EE** 的 xyz+rotvec。adapter 必须先 compose 到当前 EE 绝对位姿，再叠加伺服/抓取修正。

### 3.3 状态机

```text
INIT ──first obs──▶ STANCE ──settled──▶ LOOK ──target localized──▶ GRASP
  ▲                                      │                         │
  │                                      ▼                         ▼
  │                                   SERVO ◀── grasp chosen ── CONTACT
  │                                      │                         │
  │                                      └──── recovered ──── RECOVER
  │                                                                │
  └──────────────── reset / done ◀──────────────────────────────────┘
```

- `STANCE`：选择并平滑切换支撑姿态；默认只调 height/angle_z。
- `LOOK`：腕部/头部测量；低置信才触发微步。
- `GRASP`：采样/评分抓取位姿；输出夹爪开口/抓取轴/接近方向。
- `SERVO`：5 步 IBVS/PBVS 修正。
- `CONTACT`：法向缩幅、切向保留；滑移检测。
- `RECOVER`：场景被编辑/目标丢失；停 → 重定位 → 重规划。

### 3.4 `get_action` 伪代码

```python
class WristTriadPolicy:
    def get_action(self, obs):
        self._tick(obs)
        self._maybe_request_plan(obs)

        if self.plan is None:
            self.plan = self.vla.predict(obs)   # cold start only
            self.plan_idx = 0

        mode = self.router.select(obs, self.state)
        self.state = mode

        if mode == "STANCE":
            a_cmd = self.posture.hold_or_transition(obs, self.H_c)
        elif mode == "LOOK":
            a_cmd = self.wrist_metric.look(obs, self.H_c)
        elif mode == "GRASP":
            self.grasp = self.grasp_planner.plan(obs)
            a_cmd = self.servo.to_grasp(obs, self.grasp, self.H_c)
        elif mode == "SERVO":
            a_ff = self.plan[self.plan_idx : self.plan_idx + self.H_c]
            delta = self.servo.compute(obs, self.goal)
            a_cmd = compose_relative(a_ff, delta)
        elif mode == "RECOVER":
            a_cmd = self.recover(obs, self.H_c)
        else:  # MOVE
            a_cmd = self.plan[self.plan_idx : self.plan_idx + self.H_c]

        self.plan_idx += self.H_c
        if self.plan_idx >= len(self.plan):
            self.plan_idx = 0
            self.plan = None

        return self.adapter.to_api(a_cmd, obs, self.token)
```

规则：

- VLA 永远不阻塞 `get_action`（除冷启动）；plan 过期就用旧 plan + 伺服/姿态。
- 每个 chunk 只选一个支点；支点失败不影响返回合法动作。
- 任何异常 → 返回上一组合法 chunk 或安全 hold；绝不返回 NaN/错误形状。
- `LOOK`/`STANCE` 有最大持续时间/最大次数；超时回退 `SERVO`/`MOVE`。

### 3.5 动作适配（WLA 54D → 挑战赛 21D）

```text
WLA 54D:
  left_ee_rel[6], left_gripper[1], left_hand[6],
  right_ee_rel[6], right_gripper[1], right_hand[6],
  waist[3], torso[3], base_vxvy[2], base_wz[1],
  base_pose_rel[6], height[1], left_leg[6], right_leg[6]

挑战赛 ee 21D:
  left_ee_abs[6], right_ee_abs[6],
  left_gripper[1], right_gripper[1], pivot[7]
```

映射：

1. `left_ee_abs = compose(T_base_ee_left_current, exp(left_ee_rel))`；转 xyz+rpy。
2. `right_ee_abs` 同理。
3. gripper 直通（按挑战赛的 0–1 方向校验）。
4. `pivot = [vx, vy, angle_z, 0, 0, 0, height]`：只填语义明确的 `vx/vy/angle_z/height`，`pivot_3..5` 先置零；height 可由 stance 覆盖，vx/vy 默认 0。
5. 腿部/灵巧手在 `ee` 模式下不直接下发；若 `pivot` 内部映射到腰/腿，按单任务通道验证。

**关键细节**：WLA 的每个未来动作是“相对 plan-time 当前 EE”的位姿（compose 后才是 base 系绝对目标），不是累积增量；adapter 必须先把整个 30 步 compose 成 base 系绝对目标，再按 5 步切片。否则切片后的第 6–30 步会以错误锚点解释，产生系统性偏移。

**帧/TCP 风险**：WLA 的 EE 帧与挑战赛 `*_ee_pose_gripper_base` 帧可能差一个 TCP/夹爪长度偏移；必须用 `example_env.py` 观测和真实数据做一次手眼/工具坐标校准（平移 ≤1 cm、旋转 ≤2°）。这是 G1 的第一验证项。

**pivot 风险**：`pivot_3..5` 语义未定义；先返回零，只验证 `height/angle_z/vx/vy`。若 `height` 符号相反或单位不同，用单任务通道小步测试，不要猜。

## 4. WRIST-METRIC 细节

### 4.1 内参与畸变

- 腕部左/右内参、畸变已知（见 §1.4）；先做 `cv2.undistort` 再算射线。
- 内参是采集机器人的；评测机器人可能不同。G0 要检查跨机器人：同一已知标定板/桌面标记在 3 台机器人上的重投影误差 ≤3 px；超过则用单任务通道做一次在线偏置估计（只估 `fx,fy,cx,cy` 的小偏置，不重训）。
- 头双目已 rectified，直接用 `fx,b` 视差。

### 4.2 桌面平面

- 方法 1：在 episode 开始时，用头双目 + 机器人末端触碰/已知桌面高度得到 `n,d`；桌面高度先验 0.65–0.75 m。
- 方法 2：用腕部图像中的桌面纹理/边缘做单应，估平面法向；只在需要时。
- 方法 3：用演示统计的桌面高度范围做先验，在线用头双目修正。
- 平面误差 5 mm 会直接变成目标高度误差；G2 要求 `|Δd|≤3 mm`，否则只用相对高度/2D 伺服。

### 4.3 头双目深度

- 只在目标可见、纹理足够、视差有效时使用；透明/反光/无纹理 → 置信度低。
- 用左右一致性检查、ROI 有效像素比例、视差梯度做置信度。
- 头双目深度给腕部测量提供初值/交叉验证，不单独承担最后 2 mm。

### 4.4 腕部微步（LOOK）

```text
1. 在当前 EE 位姿附近生成 3 个观察点：
   p0 = current
   p1 = p0 + [0, +b, 0] 或 [+b, 0, 0]（横向，垂直于光轴）
   p2 = p0 + [0, -b, 0] 或 [-b, 0, 0]
   姿态保持，b=2–4 cm；速度限幅；先抬离桌面 2 cm
2. 每个点停 100 ms（3 帧），取中间帧
3. 匹配目标关键点/轮廓（ORB/光流/颜色）
4. 三角化；检查 reprojection、视差角、置信度
5. 回到 p0；如果失败，回退桌面平面
```

约束：

- 只在 `v_t < θ_v` 或深度置信度低时触发；最多 2 次/任务。
- 不在接触后做（会破坏接触）；接触前/预抓取做。
- 微步图不直接喂 VLA；VLA 输入保持 canonical 当前帧。
- 时间预算：3 点 × (移动 ~150 ms + 停 100 ms) ≈ 0.75–1.0 s；180 s 任务可接受，但不要每个任务都做。

### 4.5 手眼外参

优先级：

1. **URDF/CAD**：如果官方 G1 模型给出腕部相机 mount，直接取 `T_EW`；用重投影验证。
2. **演示数据 + 已知目标**：用头双目/桌面平面给 `X_B`，最小化腕部重投影（§2.1）。
3. **主动运动 AX=XB**：用腕部特征跟踪 + EE 位姿，解手眼；ActiveAlign-Waving 是参考。
4. **退化回退**：只用 2D 像素/桌面平面，不输出 6D 抓取。

G1 门：重投影 ≤5 px；平移误差 ≤5 mm、旋转 ≤2°；超过则关闭 6D 抓取，只做 2.5D。

### 4.6 置信度与回退

```text
if reproj > 5px or handeye_uncertain > θ:   fallback 2D/plane
if stereo_valid < 70% or disp_grad < θ:     fallback plane
if target_specular/transparent:             fallback wrist 2D + VLA
if microgait_timeout/collision:             fallback plane
```

回退不是失败：它保证 `get_action` 永远返回合法动作；WRIST-METRIC 的边际收益集中在 A 档刚体任务。

## 5. GRASP-AFFORDANCE 细节

### 5.1 离线演示先验

从 33k 成功演示提取：

- 夹爪闭合前 1–3 帧的腕部图、EE 位姿、夹爪开口；
- 抓取点相对目标 ROI 质心的位置/方向；
- 每个任务的常见抓取轴（水平/垂直/斜 45°）；
- 夹爪开口分布（左/右夹爪 0–4.5 归一化）。

不训练网络；只做分任务/分阶段的统计和最近邻检索。检索是控制器的一部分，不是第二个学习模型；若官方对“模型”作最宽解释，提交材料按 C2（确定性控制器）说明。

### 5.2 候选采样

- ROI：语言/头双目/颜色/深度边缘；无法分割 → 回退 VLA。
- 边界点：轮廓均匀采样 64–128 点，估计局部法向。
- 对跖候选：只保留 `w` 在 `[0.3 g_max, 0.95 g_max]` 的点对；避免夹爪张不开/夹空。
- 每个候选生成抓取位姿：`c`、`a`（抓取轴）、`d`（接近方向，取相机射线/表面法向的折中）、`w`。
- 用 2–3 个接近方向（顶抓/侧抓/斜抓）覆盖桌面任务。

### 5.3 评分与选择

- 先硬约束：宽度、IK、碰撞、关节限位；不满足直接丢。
- 再软评分：`S`（§2.3）。
- top-k=5，做时序滞回：连续 2 帧 top-1 一致才切换；否则保持当前抓取。
- 若 top-1 `S < θ_q` 或 top-k 方差大 → 回退 VLA 原动作，不硬抓。

### 5.4 执行

```text
1. 预抓取：到抓取点上方/侧方 3–5 cm，夹爪开口到 w+margin
2. 对准：用 SERVO 的 IBVS/PBVS 把抓取轴/中心对到腕部目标图
3. 闭合：按抓取位姿闭合夹爪；监测夹爪位置/电流（若 API 有）或视觉滑移
4. 轻抬：抬 1–2 cm，检查物体是否随动；不随动 → 重抓/换候选
5. 进入搬运/放置：交回 VLA plan
```

API 没有力/触觉；滑移检测只能用视觉（腕部图中物体相对夹爪的位移）和第 11 轮的 `r_grasp` 残差。

## 6. POSTURE-GAIT 细节

### 6.1 从演示提取姿态

对每个任务：

- 读取 `action.pivot` 的 `height/angle_z/vx/vy` 分布；
- 读取 `observation.state.lower_body` 的腰/腿分布（只作观测/验证，不作命令）；
- 按任务阶段（接近/操作/放置）分段，取每段的中位姿态；
- 聚成 12–18 个 stance（3 高度 × 3 yaw × 2 前后），每个 stance 记录任务/阶段先验。

### 6.2 在线选择

```text
candidates = stance_library[task_id]
for s in candidates:
    R = ik_reachability(target_b, s)
    V = visibility(target_b, s, wrist/head)
    B = stability_margin(s)
    C = transition_cost(s, current)
    score = R + λ_v V + λ_b B - λ_c C
choose s* with hysteresis
```

- `target_b` 来自 WRIST-METRIC/头双目；没有目标时用任务先验。
- `ik_reachability`：G1 URDF + 双臂 IK；检查目标是否在舒适工作空间、是否接近关节限位/奇异。
- `visibility`：腕部/头部视锥 + 桌面遮挡的粗几何；不训练视觉模型。
- `stability`：支撑多边形/CoM 粗检查；桌面任务不做动态步态。
- `transition`：0.5–1.0 s 平滑插值；一次 episode 最多 1–2 次。

### 6.3 安全

- 先只调 `height` 与 `angle_z`；`vx/vy` 默认 0。
- `height` 限幅 0.62–0.74 m；速度限幅；切换前抬臂/收腕，避免碰桌。
- 切换后等待 3–5 帧稳定，再进入 LOOK/GRASP。
- 任何超时/碰撞/姿态误差大 → 回退当前姿态，不继续切。
- `pivot_3..5` 先零；单任务通道逐维验证后再开。

### 6.4 与 VLA 的关系

VLA 仍然输出 30 步双臂/夹爪/pivot plan；POSTURE-GAIT 只在 episode 开始或路由判定“够不到/被挡”时**覆盖 pivot**，双臂动作仍由 VLA plan + SERVO 决定。这样：

- 不改变 VLA 的语义意图；
- 不引入第二个学习模型；
- 姿态切换是慢时间尺度，不打断 5 步快环；
- 若姿态覆盖导致 VLA plan 失效，触发一次 VLA 重规划（新图 + 语言）。

| 头双目深度误差 | 0.5 m: 15.2 mm/px；1.0 m: 61.0 mm/px | 证明头双目不够最后 2 mm |
| 32 任务 pivot | 18/32 高度跨度≥5 cm；22/32 yaw 跨度≥0.79 rad；20/32 base `vx/vy`>0.01 | 证明 POSTURE-GAIT 有数据基础 |
| 榜单回归 | R²>0.9999996；平均相关 0.0975；232/256 非 10% 倍数 | 证明榜单是预览，不可当难度表 |

### 7.2 仿真

| 实验 | 变量 | 指标 | 门 |
|---|---|---|---|
| 腕部测量 | 平面/双目/微步；噪声；手眼误差 | 深度误差、重投影、失败率 | G2 |
| 抓取评分 | 候选数、评分权重、分割噪声 | top-1 可行率、抓取成功率 | G3 |
| 姿态 | 12–18 stance；height/yaw；目标位置 | IK 可达率、可见率、稳定裕度、切换时间 | G4 |
| 路由 | 残差阈值、滞回 | 分类 AUROC、误切换、任务成功 | G5 |
| 伺服 | `H_c`/`K`/`τ` | 横向≤2 mm、深度≤3 mm、2 s≥95% | G6 |
| 扰动 | 位置/遮挡/背景/目标移动/人手 | 恢复率、检测延迟 | G7 |

每个组合至少 50 次仿真；报告成功率、收敛时间、超调、恢复率、p99。仿真只用于找稳定域和相对排序，不预测真机绝对成功率。

### 7.5 消融

1. WRIST-METRIC on/off（平面 vs 双目 vs 微步）。
2. GRASP on/off；抓取评分 vs VLA 原动作。
3. STANCE on/off；只 height vs height+yaw vs +base。
4. ROUTER on/off；固定 SERVO vs 路由。
5. 相对目标 vs 绝对目标。
6. 5 步 chunk vs 30 步 chunk。
7. 手眼外参 URDF vs 主动标定。
8. 微步 LOOK on/off（检验分布偏移风险）。

### 7.6 门 G0–G9

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | 腕部内参跨机器人一致？ | 重投影 ≤3 px；ROI 有效 ≥70% | 在线偏置/只用 2D |
| G1 | 手眼外参可用？ | 重投影 ≤5 px；平移 ≤5 mm/旋转 ≤2° | 关闭 6D 抓取，只做 2.5D |
| G2 | 腕部测量够准？ | 5–10 cm 深度误差 ≤2 mm；15 cm ≤5 mm | 只用桌面平面/头双目 |
| G3 | 抓取评分可信？ | 离线 top-1 可行 ≥80%；仿真抓取 ≥70% | 回退 VLA 原动作 |
| G4 | 姿态规划有效？ | 低高度任务 IK 可达 +20%；无稳定违规；切换 ≤1 s | 只调 height/waist；关 base |
| G5 | 路由可解释？ | 离线 AUROC ≥0.85；误切换 ≤10% | 固定 SERVO，不做路由 |
| G6 | 伺服收敛？ | 横向 ≤2 mm、深度 ≤3 mm、2 s ≥95%；RTT 0–150 ms 稳定 | 降增益/加 chunk；只做 PBVS |
| G7 | 真机单任务涨点？ | ≥2/4 任务 +10pp；ZipUp 不回归 >5pp | 不提交 WRIST-TRIAD |
| G8 | 延迟可接受？ | p99 ≤150 ms；timeout 不升 | 加 chunk/降分辨率/关 LOOK |
| G9 | 32 任务干跑稳定？ | N 端口隔离、reset 干净、内存不涨 | 回退基线 |

### 8.2 失败模式分诊

| 失败模式 | 典型任务 | 该投什么 | 不该投什么 |
|---|---|---|---|
| 最后接触/插入/挂/叠/拉链/锁 | PlugInEthernet、HangCup、ZipUp、StackBowls、Unlock、ArrangeTestTubes、ToolboxStorage | WRIST-METRIC + SERVO + 相对目标 | 更大 VLA、更多语义数据 |

| 位置/人为干扰 | 5 类泛化轴；human_1/4 | 重定位 + 恢复 + 相对目标 | 固定轨迹、开环 chunk |
| 背景/干扰物/未见物品 | FruitSorting、ColorArrangement、OrganizeTools | VLA 数据增强/微调 + 局部 ROI | 纯几何伺服 |
| 变形/语义/长程 | FoldTowel、PackBag、SpellRobot、ConveyorSorting | VLA 基座 + 任务数据 | 6D 物体位姿网络 |

### 8.3 边际收益与预算

| 方案 | 成本（估算） | 预期收益 | 建议 |
|---|---|---|---|
| 官方 WLA 直接适配 | 1–2 人周 | 基线；可能 20–30% | 必做；先锁基线 |
| WLA action-head 微调 | 2–3 GPU 周 + 1 人周 | +1–3pp（未知） | 做；不指望它解决最后 3cm |
| WRIST-METRIC | 1–2 人周 + 1 次标定 | A 档 +2–5pp（估计） | 主投；先做 |
| GRASP-AFFORDANCE | 2–3 人周 | 抓取类 +5–10pp（估计） | 主投第二 |
| POSTURE-GAIT | 1–2 人周 | 够不到类 +5–10pp（估计） | 主投第三 |
| ROUTER | 1 人周 | 防止负迁移；+1–3pp | 主投 |
| 完整世界模型 | 8+ GPU 周 | 不确定；延迟更差 | 不做 |
| 连续步态 RL | 4+ GPU 周 | 桌面不需要 | 不做 |
| 32 任务各训策略 | 规则禁止 | — | 不做 |

收益算术：

- 若 10 个接触任务各 +10pp：`10/32×10 = +3.1pp`；
- 若 19 个 A 档各 +8pp：`19/32×8 = +4.75pp`；
- 人为干扰轴 +10pp：`0.2×10 = +2pp`；
- 姿态/抓取若只对 8 个任务有效：`8/32×10 = +2.5pp`；
- 保守合计 **+3–6pp**，乐观 **+7–9pp**；必须用配对 A/B 证明。

## 9. 风险与合规

### 9.1 单模型合规的三种模式

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 演示统计/相位标签只离线；线上只有 VLA | 最低 | 保守备选 |
| C2 确定性控制器 | 腕部测量/抓取评分/姿态选择是几何/控制律，无学习权重；VLA 是唯一学习模型 | 低；需向官方说明 | 主推 |
| C3 同 checkpoint 特征 | 目标描述子用 VLA 同一 checkpoint 的 encoder，不加载第二个模型 | 低–中；需说明 | 需要强描述子时用 |

禁止：加载第二个学习策略/残差网络/独立视觉编码器做在线决策。

### 9.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 手眼外参错 | 腕部 3D 偏 1–2 cm | URDF 先验 + 主动标定 + 重投影门；误差大只用 2D/桌面平面 |
| 腕部内参跨机器人不一致 | 2D→3D 偏 | G0 三机验证；在线小偏置；只用 2D 兜底 |
| 微步造成 VLA 分布偏移 | 成功率反降 | 微步只用于确定性测量；VLA 输入保持 canonical；I6 才做微调 |
| 抓取分割错 | 抓空/碰撞 | 只对刚体/清晰轮廓启用；低置信回退 VLA；夹爪宽度硬约束 |
| 抓取评分过拟合 | 换物体失败 | 任务/阶段分组验证；top-k 滞回；不见物品只用 VLA |
| 姿态切换超时/失稳 | 180 s 预算/安全 | 先只调 height/angle_z；限速/限幅；一次 episode ≤2 次；base 默认 0 |
| `pivot_3..5` 语义未知 | 动作异常 | 先返回零；单任务通道逐维验证；不猜符号 |
| `pivot` 高度方向/单位不同 | 蹲反/过冲 | 单任务通道小步测试；限幅；失败回退零 |
| 单模型解释 | 被判第二个模型 | C1/C2/C3；提交材料写清；抓取/姿态无学习权重 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |
| 榜单是预览 | 误判难度 | 不把榜单任务排名当实测；只用上限信号 |
| 透明/反光/变形 | 测量/抓取失败 | 只对刚体启用；腕部 2D + 桌面平面兜底；ZipUp 只做回归 |
| 远程 RTT 高 | 反馈慢 | 5 步 chunk；RTT 测量；预测补偿；回退 chunk 8–10 |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split |
