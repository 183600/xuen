# 第 1 轮 · CARE-GPR：从「终端放置」转到「接触感知的云边远程执行」

> 检索/复核日期：2026-10-25（UTC）。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「最优控制」「云边协同」「力控」。我先用它们去撞官方手册和提交接口，结果不是「再加三个模块」，而是**修正了上一轮的一个核心判断**：排名不是成功率与步骤分的加权和，而是成功率优先、步骤分只破同分；API 没有力/力矩；N 台机器人要求 N 个端口并发。于是主押注从「终端放置的步骤分杠杆」改为「让远程位置接口在接触和延迟下仍然可靠」。

## 0. 本轮先核实：七个改变判断的事实

### 0.1 手册可读，排名规则是「成功率优先、步骤分破同分」

官方中文手册（[S2]，英文版 [S3]）1.2 写得很清楚：

> 「实时榜单按32个任务的总平均成功率进行排序，成功率相同时按总平均步骤分排序，若仍相同，则提交日期较早的模型排序靠前。」

这句话把上一轮的「排名 = 成功率与步骤分综合排序」改成了**字典序**：先看成功率，再看步骤分。首页文案仍写「按平均成功率与步骤分综合排序」（[S11]），但手册是更具体的规则，应以手册为准。这个差别不是文字游戏：它意味着**不能用步骤分去换成功率**，也意味着上一轮把「终局步骤占步骤分 39.8%」直接当成「杠杆」是过度解读。终局步骤仍然是 32/32 任务的成功闸门（成功=所有步骤完成），但它的边际价值取决于「有多少 episode 能走到终局」这个 q，而 q 必须实测，不能假设 0.5–0.7。

### 0.2 每个任务 10 次、五轴各 2 次、共 320 次计分

手册 2.1：每个任务执行 10 次独立运行，包含 5 种泛化类型（位置、干扰物、桌面背景、未见物品、人为干扰），每种各 2 次；单次真机最长 180 秒，超时记失败，步骤分照算（[S2]）。这给出了三个硬约束：

- **32 × 10 = 320 次计分 trials**。总体成功率的二项标准误在 p≈0.3 时约 2.56pp；+3pp 只有约 1.2 个标准误，+5pp 才接近 2 个标准误。小改进会被噪声吞掉，必须做**跨任务的稳健改进**，而不是单任务 trick。
- **每个任务只占 3.125%**，但**每个泛化轴占 20%**（若所有任务都栽在同一轴）。一个系统性弱轴会把成功率上限压到 80%。这是 max-min 问题，不是平均值问题。
- **人为干扰轴 = 64/320 = 20%**。官方备注给出了逐任务的两条 human 剧本（human_1/human_4），这正好对应 human 轴的两次运行；第 7 轮的 NRB（官方备注忠实恢复库）从「锦上添花」升级为「必须拿下的 20%」。

### 0.3 API 没有力/力矩，只有位置

提交模板的观测目录（[S4]）只有：四路 RGB、双臂 7 维关节位置、双臂 6 维 EE 位姿（base 系）、夹爪开度、下半身 15 维、语言字符串。动作目录只有：关节位置或 EE 位姿（二选一）、夹爪位置目标、pivot。**没有 F/T、没有关节力矩、没有触觉、没有夹爪力**。数据集侧也一样（[S8]）：`observation.state.*` 和 `action.*` 里没有任何 force/torque 字段。

Dex1-1 本体其实有 5–120N 可调夹持力、1kHz 力位混合控制和力矩反馈（[S12]），但挑战接口不暴露这些字段，也不允许我们设定力上限。所以本轮对「力控」的正确理解不是「写一个力矩控制器」，而是：

- **隐式力控（implicit force control）**：用位置目标的柔顺化、跟踪误差、夹爪开度停滞、物体运动与指令运动的偏差，来估计接触状态；用外层导纳/阻抗滤波和任务原语（螺旋搜索、摆动拔出、缓放静置）来实现「类力控」行为。
- **身体作为力源**：`action.pivot` 和下半身/腰部是可用的；拔出网线、电池、插头这类任务，可以用「手臂保持 + 身体后撤/腰部俯仰」产生受控拉力，而不是只靠手臂。
- **实验室力蒸馏**：如果规则允许外部数据，用带 Dex3-1 触觉/力反馈的 G1 采集接触密集演示，训练一个 force-aware teacher，再把「力相关性 token」蒸馏进 Dex1 的视觉-本体学生（HapticVLA 路线，[S25]）。这是「产学研」在力控上的具体用法。

### 0.4 N 台机器人、N 个连续端口、延迟会被记录

提交模板第 5 节（[S4]）：评测在 N 台测试机器人上随机顺序运行，N 由官方另行公布；提交必须从 8765 起暴露**恰好 N 个连续端口**，每个端口独立完成一台机器人的完整交互；不同端口可能同时被调用，**必须处理并发、必须做 episode 状态隔离**。第 6 节还写明：每步 `get_action` 的**延迟和内容都会被记录**，延迟的稳定性、返回动作的统计规律性可能随成绩一起展示，并影响结果可信度。

这直接给了「云边协同」一个真实落点：不是「在机器人上跑边缘模型」（官方不让我们在机器人上部署代码），而是**在我们自己的服务侧做「共享慢脑 + 每端口快脑」**。6B 模型不必为 N 个端口复制 N 份；重模型在云端异步出语义特征，每个端口只跑一个轻量快脑 + 状态机 + 合规层，临界路径不经过 6B 的前向。N 端口并发、延迟抖动、状态隔离，都是这一轮必须回答的工程-研究问题。

### 0.5 数据总量 33,276 条 / 169.3 小时，与官网 32k/169h 对齐

我用 HF API 把 32 个数据集的 `meta/info.json` 全部拉了一遍（[S7][S8]）：合计 **33,276 条 episode、18,282,246 帧、30fps 下 169.3 小时**；HangCup 1,043 条 / 194,564 帧，`lastModified` 2026-10-14。官网写「32000 演示样本 / 169 小时」（[S1]），是四舍五入。第 7 轮的「33k / 169h」判断成立，且现在有逐任务总数，可用于按任务/按轴加权采样。

### 0.6 榜单仍是占位；「榜首 <30%」只能当量级前提

`leaderboard.html` 和 `runs.html` 在 2026-10-25 仍是「即将发布 / Coming Soon」（[S9][S10]）；`leaderboard_data.json` 仍是脚本生成的 8 个占位模型、256 条 task_metrics。公开渠道没有任何真实头部方案、技术报告或参赛代码（我搜了官网、GitHub、知乎/B站、arXiv，均无）。因此：

- 题设说「榜首成功率也不到 30%」，我把它当作**量级前提**使用，但不把它归因到某个具体团队或方法；
- 上一轮把占位榜的「步骤分 − 成功率 ≈ +8.6pp」解释成「大部分失败倒在最后一步」，这个解释在算术上很可能是反的（见 §1.3），本轮不再使用；
- 对「头部方案」的分析只能是**基于官方基座、数据和规则的推断**，必须标明「无公开证据」。

### 0.7 立体相机可用，但标定未公开

数据集有四路相机：`head_stereo_left/right` + `wrist_left/right`（[S8]）；API 对应 `cam_left_high/right_high` + `cam_left_wrist/right_wrist`（[S4]）。G1/G1+ 的头部双目在型号页写 60mm baseline、2MP（[S13]）；数据集里还有 `state_d435` 位姿，说明头部可能还有一颗 D435。无论具体是双目还是 D435 的立体像对，**两路高位相机是立体对**，可以用来做度量深度。但 `meta/` 里只有 `info.json`、`stats.json`、`tasks.parquet`，**没有相机内参/外参**（[S7]）。所以 SMG（立体度量 grounding）的第一步是标定：用 G1 的 URDF/官方安装尺寸做近似，或在实验室用棋盘格做一次离线标定；再不行就用 foundation stereo / 单目深度 + 机器人几何尺度兜底。这是中等风险、中等收益的支撑件，不是主押注。

## 1. 上一轮哪里对、哪里错

### 1.1 对的：终局步骤是成功闸门，且跨五轴

32 个任务的 `score_steps` 满分都是 100，成功=所有步骤完成（[S35]）。终局步骤合计 1275/3200 = 39.8%，其中 28 个是放置/插入/堆叠/闭合类，4 个是拔出/取出/翻转/倾倒类（T05/T11/T12/T14）。无论排名怎么算，**终局步骤不完成就不算成功**；而五个轴都会走到终局，所以终端能力确实是跨轴资产。这一点保留。

### 1.2 错的：把「步骤分权重」当成了「排名权重」

上一轮的推理是：

```text
终局步骤 = 39.8% 的步骤分
放置类 = 59.7% 的步骤分
=> 终局放置 +Δ ≈ 全局 +Δ×q，单轴 +Δ 只有 +Δ/5
=> 终局放置的杠杆是单轴的 2.5–3.5 倍
```

这套算术在「步骤分是排名主项」时成立；但手册明确成功率优先、步骤分只破同分（[S2]）。所以正确的表述是：

```text
成功率 S = 所有步骤完成的 episode 比例          # 排名第一关键字
步骤分 P = 逐步部分分                            # 仅当 S 相同才比较
```

终端放置仍然重要，因为它是 S 的闸门；但它不再是「39.8% 的排名权重」。把资源从「补最弱轴」全部转到「终端放置」，在成功率优先的规则下可能错配——如果 q 很低（模型根本走不到终局），终端放置的边际收益会大打折扣。

### 1.3 更严重的：占位数据的「+8.6pp」可能指向早期失败，而不是最后一步

假设步骤分是 0–100、成功 episode 得 100，则失败 episode 的平均步骤分为：

```text
P_fail = (P - 100·S) / (1 - S)
```

代入占位榜头部 S=0.297、P=0.390：

```text
P_fail = (0.390 - 0.297) / 0.703 = 0.132   # ≈ 13 分
```

也就是说，如果这组数字是真的，失败 episode 平均只完成了约 13% 的步骤——**失败发生在很靠前的位置，而不是最后一步**。这和上一轮「大部分失败倒在最后一步」的解读正好相反。当然，占位数据是脚本生成的，不能据此下结论；但这个反例说明：**必须用 SSG 的步骤级日志去实测 q 和失败分布，不能再用占位数据做先验**。这是本轮把「阶段级可靠性」放在「终端放置」之前的原因。

### 1.4 所以主押注改成：阶段级可靠性 + 接触 + 服务

新的判断是：

- 终端放置是**必要闸门**，但不是唯一瓶颈；首步抓取/接近、接触阶段、人为干扰恢复、长程步骤累积、远程延迟，都可能吃掉大量 episode。
- 五轴各 20%，任何一轴系统性失败都会把成功率上限压到 80%；所以要做的是**跨轴稳健**，不是单点刷分。
- 力控和云边协同不是「锦上添花」：它们分别对应「接触阶段」和「远程服务」这两个此前没有专门处理的结构性失败源。
- 最优控制不是「上运行时 MPC/仿真」；而是在**任务级**（180 秒预算下的重试/推进/回滚）和**块级**（RTC 前缀冻结 + 最小加加速度/速度加速度约束的 chunk 融合）做两层轻量优化。

## 2. 三个灵感词，各自钉到约束上

### 2.1 最优控制：两层，不上仿真

**任务级 SAEC（Score-Aware Episode Control）**：把每个任务看成一个有限时域的 MDP，状态是 SSG 步骤 `s_t` + 剩余时间 `τ` + 谓词置信度；动作是 `advance / retry / regrasp / rollback / abort`；奖励是成功（第一目标）+ 步骤分（破同分）；约束是 180 秒。用离线估计的每步成功率/耗时做动态规划，得到「什么时候重试、什么时候推进、什么时候放弃当前步」的阈值策略。因为成功是字典序第一，最优策略会倾向于**在谓词未确认前绝不推进**、**在时间 guard 内优先重试当前步**，并在检测到 human 撤销（谓词 1→0）时回滚。这个层是确定性的，不需要新模型，直接对着评分规则。

**块级 OCP（chunk blending）**：远程 API 是「一次 `get_action` 返回一个 chunk，评测端按顺序执行」。如果新 chunk 和正在执行的 chunk 在边界上不连续，就会出现急停/抖动，接触任务尤其受伤。把「冻结前缀 + 新 chunk」的融合写成一个小的约束优化：

```text
min_a  ||a - a_new||² + λ1||Δa||² + λ2||Δ²a||²
s.t.   a[0:k] = a_exec[0:k]          # 已承诺的前缀
       |Δa| ≤ v_max, |Δ²a| ≤ a_max   # 速度/加速度约束
       joint limits / table keep-out
```

这个 QP 很小（chunk 8–32 步、7–14 维），CPU 上毫秒级；它不是「用仿真做 MPC」，而是**在动作块边界做最优控制**。它和 RTC/VLASH 是互补的：RTC 解决「怎么生成下一块」，OCP 解决「生成后怎么无缝接上」。

### 2.2 云边协同：共享慢脑 + 每端口快脑

官方不让我们在机器人上跑代码，所以「边」不是机器人本体，而是**我们服务侧的每端口快速路径**。一个可落地的架构是：

```text
云端（共享，低频）：6B WLA 的 ER-1/VLM 主干 → 任务/场景/步骤语义特征
边缘（每端口，高频）：轻量视觉编码器 + 本体编码 + 交叉注意力 → 动作残差/chunk
                      + SSG 状态机 + IFC 合规层 + SAEC 预算控制
```

训练时用 CloudEdgeVLA 的「新鲜/延迟帧配对」目标（[S22]）：当前帧和随机延迟帧配同一个当前动作目标，让云端特征保留任务级信息、边缘头提供状态敏感修正。推理时云端特征可以慢（甚至跨 chunk 复用），边缘头用最新观测出动作；临界路径不经过 6B 前向。N 个端口共享云端主干，但每个端口有独立的边缘头状态/SSG 状态/缓存，满足状态隔离。

这条路线的证据链是完整的：RTC（[S15]）证明异步执行 + 前缀 inpainting 对延迟鲁棒；VLASH（[S17]）证明用上一块动作把机器人状态前滚、按执行时刻的状态出动作，可以把反应延迟降一个量级；CloudEdgeVLA（[S22]）证明「慢语义 + 快修正」在 40 步延迟下仍能保留 63.8–78.0% 的成功率，而 VLASH 只有 6.4%、单路径基线只有 3.0%；VLA-ULAP（[S23]）证明云端 VLA + 本地超轻量预测在延迟/能耗上可行。我们要做的不是发明这些方法，而是把它们**拼成适合 UniBot 远程 API 的单 checkpoint 服务架构**。

### 2.3 力控：没有 F/T，就做「隐式力控 + 身体力源 + 实验室蒸馏」

**接触估计器**（确定性/小头）：对每一帧，计算三个代理量：

```text
e_track = || EE_obs(t+1) - EE_cmd(t) ||        # 位置跟踪误差（接触/受阻）
g_stall = 1[夹爪在闭合指令下开度停滞]          # 夹住/顶住
v_obj   = 腕部视角中物体相对 EE 的运动           # 物体是否跟着走
contact_score = f(e_track, g_stall, v_obj)      # 校准到 [0,1]
```

`e_track` 是最接近「力」的代理：位置控制器在接触时会被环境顶住，实际 EE 落后于指令；落后量 × 关节刚度 ≈ 接触力。我们可以在实验室用外部力传感器标定这条映射（G1 + Dex1，几百个接触样本即可），得到一个小的回归/查表，不需要挑战数据带力标签。

**导纳滤波**：把策略输出的位置目标 `x_ref` 变成 `x_cmd`：

```text
M ẍ_cmd + D ẋ_cmd + K (x_cmd - x_ref) = -F_est
```

自由空间用高刚度 K（跟得紧），接触阶段用低刚度 K（让得开）；`F_est` 来自接触估计器。因为低频（API 调用率），用一阶/二阶离散滤波即可，不需要实时力矩环。这样在位置接口上模拟出「柔顺」。

**任务原语**：按 SSG 步骤相位触发：

- 插入（T10 插头、T26 网线、T13 试管）：对准 → 小幅螺旋搜索（平面内）+ 微进给 → 检测到 `e_track` 下降/物体就位 → 停止。
- 拔出（T05 网线、T11 电池、T30 图钉）：夹紧 → 小幅摆动/扭转破坏静摩擦 → 手臂后撤 + 身体后撤（WBCL）→ 检测到物体位移。
- 闭合（T19/T23/T31 拉链）：夹住拉链头 → 低刚度牵拉 + 小幅横向摆动 → 谓词确认。
- 倾倒（T14 药瓶、T32 注射器）：对准 → 缓慢倾斜 → 停顿/轻敲 → 谓词确认。
- 放置（T27 叠碗、T21 盘子、T07 相框）：OPT 位姿 → 低刚度下降 → 接触检测 → 缓放 → 静置 → 稳定性校验。

**身体力源（WBCL）**：`action.pivot` 和腰部/下肢是可用的。拔网线/电池这类任务，手臂的力臂和行程有限，身体后撤可以提供更大、更可控的拉力；插入时用腰部高度微调对准。这是一个被大多数队伍忽略的自由度，且完全在 API 内。

**实验室力蒸馏**：如果规则允许外部数据，用带 Dex3-1 触觉的 G1 采集接触密集演示，训练 force-aware teacher，再把触觉 token 蒸馏进 Dex1 学生（HapticVLA，[S25]）。这条路线把「力控」变成「数据/蒸馏」问题，而不是「接口没有力传感器」的死结。

## 3. 本轮主判断：CARE-GPR

把上面的东西合成一个系统：**CARE-GPR（Contact-Aware Remote-Edge GPR）**。一句话：

> **用「共享 6B 慢脑 + 每端口轻量快脑」解决远程延迟/N 端口并发，用「推测式滚动分块 + 块级 OCP」解决 chunk 边界，用「隐式力控 + 身体力源」解决接触阶段，用「SSG + SAEC」把 180 秒花在真正的成功闸门上；终端放置（PGL/OPT/SVL）保留，但从「唯一主押注」降为「必要闸门之一」。**

为什么这比第 7 轮的「终端放置优先」更该做：

| 维度 | 第 7 轮 PILOT-GPR | 本轮 CARE-GPR |
|---|---|---|
| 排名模型 | 成功率 + 步骤分加权 | 成功率优先，步骤分破同分（手册） |
| 主瓶颈 | 终局放置 | 阶段级可靠性：首步/接触/恢复/延迟 |
| 力控 | P5 一条对策 | 独立子系统（隐式力控 + WBCL + 蒸馏） |
| 部署 | FLEET 检查单 | DR-VLA 双速率 + SRC 分块（研究问题） |
| 最优控制 | 运行时 MPC（已砍） | 任务级 SAEC + 块级 OCP（轻量） |
| 失败归因 | 占位数据推断 | SSG 步骤级实测 q，禁止占位推断 |

## 4. 保留、升级、修剪

**保留**：GPR-VLA 主干、WLA-1.0-Base 底座、TLE/ACP/GF 数据引擎、AH-TP、合规开关；SSG、PGL、OPT、ICR、SVL、NRB、L2L、DebugLoop。

**升级**：

- SSG → 阶段级失败归因 + SAEC 的状态机；
- PGL/OPT → 加 SMG 立体度量、接触感知释放；
- ICR → reset 时预取 + 每端口缓存；
- SVL → 接 IFC 的缓放/稳定性/重试；
- NRB → 对齐「每任务 2 次 human」的 64/320 trials；
- L2L → 加 Dex3 触觉教师 → Dex1 学生的力蒸馏；
- DebugLoop → 3 任务 × 2 轴的阶段诊断，不再只做「发布门」；
- FLEET → 从检查单升级为 DR-VLA 服务架构（共享主干、每端口边缘头、状态隔离、动态批处理、健康检查）。

**修剪**：

- 「终局放置 = 39.8% 步骤分 → 2.5–3.5 倍杠杆」的表述（排名规则不支持）；
- 用占位榜「步骤分 − 成功率」推断失败位置（算术上可能反了，且数据是合成的）；
- 「真力矩力控」（API 没有 F/T/力矩）；
- 「机器人上的边缘推理」（官方不允许在机器人上部署代码）；
- 运行时 MPC / 全仿真闭环（仍然太重，且没有可靠的接触仿真）；
- 全 32 任务高保真孪生、自由仿真数据、仿真 RL、每任务 LoRA、WMA-0 进主路径。

## 5. 一句话押注

**最值得押注的是把「云边双速率 + 接触感知分块执行」做成单一 checkpoint 的推理外壳：让 6B 慢脑在云端异步出语义，让每端口轻量快脑在 API 边界用最新观测做残差与合规控制，再用 SSG/SAEC 把 180 秒预算花在真正的成功闸门上——它同时解决 N 端口并发、无力矩反馈和阶段级可靠性三个结构性问题。**

## 摘要

CARE-GPR 的核心判断是：UniBot 的难点不是「再训一个更大的 VLA」，而是**让一个 6B 通才策略在官方远程位置接口、N 端口并发、无力/力矩反馈、180 秒预算和五类分布偏移下，稳定地走完每个任务的评分步骤**。因此方案由五个互相咬合的部分组成：

1. **DR-VLA（Dual-Rate VLA）**：云端共享 6B 慢脑异步出语义特征，每端口轻量快脑用最新观测做动作残差；解决远程延迟、N 端口并发和单模型约束。
2. **SRC（Speculative Receding-horizon Chunking）**：RTC 前缀冻结 + VLASH 状态前滚 + 自适应 chunk + 块级 OCP 融合；解决 chunk 边界抖动和「观测-执行」时差。
3. **IFC（Implicit Force Control）**：用跟踪误差、夹爪停滞、物体运动做接触估计，外层导纳 + 任务原语 + 身体后撤/腰部微调，把位置接口变成「类力控」；解决无力反馈下的插入/拔出/闭合/放置。
4. **SAEC（Score-Aware Episode Control）**：在 SSG 步骤图上做有限时域 MDP，成功优先、步骤分破同分、180 秒硬约束；解决「什么时候重试/推进/回滚」。
5. **SMG（Stereo Metric Grounding）**：用头部双目做度量深度、物体/容器 6D 位姿和几何优先抓取；解决空间 grounding 和透明物体。

保留并升级第 7 轮的 SSG、PGL、OPT、ICR、SVL、NRB、L2L、DebugLoop、GPR-VLA/WLA；修剪「终局放置 = 39.8% 步骤分 → 2.5–3.5 倍杠杆」的排名假设、占位榜步骤分推断、真力矩力控、机器人端边缘推理、运行时 MPC/全仿真。

**可证伪的主预测**：在官方调试通道上，CARE-GPR 相对「WLA-1.0 直接微调 + 同步整块推理」基线，在**位置 + 人为干扰**两轴上至少 +5pp 成功率；若延迟注入 80ms 时 DR-VLA/SRC 没有把 chunk 边界 jerk 降低 30% 以上，则这两个组件应被砍掉。

## 2. 评分算术与瓶颈模型

### 2.1 字典序排名

设模型 i 的总平均成功率为 `S_i`，总平均步骤分为 `P_i`。排名规则是：

```text
i ≻ j  ⇔  S_i > S_j
        或 (S_i = S_j 且 P_i > P_j)
        或 (S_i = S_j 且 P_i = P_j 且 t_i < t_j)
```

这是**字典序**，不是 `αS + (1-α)P`。其含义是：1pp 成功率的边际价值是无穷大的（相对于步骤分）；步骤分只在成功率完全相同时才有用。因此：

- **不要**为了 +5 步骤分去牺牲 -1pp 成功率；
- **不要**把「终局步骤占步骤分 39.8%」直接翻译成「终端放置是排名的主杠杆」；
- 步骤分仍然值得优化，但它是**第二目标**，且在成功率相同的模型之间才生效。

### 2.2 统计功效

| 层级 | trial 数 | p=0.3 时 SE | 95% CI 半宽 | 能测出的最小差异（约） |
|---|---:|---:|---:|---:|
| 总体 | 320 | 2.56pp | ±5.0pp | ~7pp |
| 单轴 | 64 | 5.73pp | ±11.2pp | ~16pp |
| 单任务 | 10 | 14.5pp | ±28pp | ~40pp |
| 单任务单轴 | 2 | 32.4pp | ±63pp | 不可测 |

CI 半宽是对单个比例的正态近似；「最小差异」是两个独立比例比较的近似（1.96×√(2p(1-p)/n)）。

**含义**：

- 总体 +3pp 只有约 1.2 个 SE；单次评测可能不显著。+5pp 约 2 个 SE，才接近可辩护。
- 单任务/单轴的数字只能当**方向性诊断**，不能当排名承诺。
- 跨任务一致性（例如 20/32 任务都 +1 次成功）比总体 +3pp 更有说服力；应做配对/分层分析。
- 若官方只跑一次，我们必须用**离线 + 调试 + 跨任务一致性**三条证据来支撑结论，而不是只看一次榜单。

### 2.3 上一轮步骤分推断的修正

上一轮看到占位榜头部 `S=0.297, P=0.390`，推断「步骤分 − 成功率 ≈ +8.6pp → 大部分失败倒在最后一步」。这个推断有问题。

假设步骤分是 0–100、成功 episode 得 100，则失败 episode 的平均步骤分为：

```text
P_fail = (P - 100·S) / (1 - S)
       = (0.390 - 0.297) / 0.703
       = 0.132   # ≈ 13 分
```

也就是说，如果这组数字是真的，失败 episode 平均只完成了约 13% 的步骤——**失败在很靠前的位置**，而不是最后一步。这与上一轮的解读相反。

但占位数据是脚本生成的，不能据此下结论。正确的结论是：

1. **占位数据不能用于推断失败分布**；
2. **必须用 SSG 的步骤级日志实测 q_k**；
3. 在实测之前，不能把资源全部押在终端放置；
4. 若调试发现 q_1（首步抓取/接近）很低，优先修首步；若 q_term 很低而 reach 很高，才优先修终端。

### 2.4 每任务成功率的分解

对任务 t，设步骤 k 的条件完成概率为 `q_{t,k}`（在前序步骤完成的条件下）。若近似独立：

```text
S_t = Π_{k=1..K_t} q_{t,k}
reach_{t,k} = Π_{j<k} q_{t,j}          # 走到第 k 步的概率
S = (1/32) Σ_t S_t
```

终端步骤的边际收益：

```text
∂S/∂q_{t,K} = reach_{t,K} / 32
```

首步的边际收益：

```text
∂S/∂q_{t,1} = S_t / (32·q_{t,1})
```

**关键**：终端步骤的杠杆是 `reach`，不是 39.8%。如果 `reach` 只有 0.3，终端 q 提升 10pp 对总体 S 的贡献是 `0.3×0.1/32 = 0.09pp`（单任务）；而首步 q 从 0.5 提到 0.6，对同一任务的贡献是 `S_t/(32×0.5)×0.1`，S_t=0.3 时约 0.19pp。**先修 q 最低的步骤，而不是权重最高的步骤。** 步骤权重只在同分时用于 P，不影响 S 的边际。

### 3.1 总览

```text
┌──────────────┐   4 RGB + proprio + language    │
│  Evaluator   │ ───────────────────────────────┼──────────────┐
│  (N ports)   │                                ▼              │
│  8765..      │                     ┌──────────────────────┐  │
└──────┬───────┘                     │  Edge head (per port)│  │
       │ action chunk                │  small ViT + cross-attn│ │
       ▼                             │  → action chunk      │  │
┌──────────────┐                     └──────────┬───────────┘  │
│  Robot       │                                │              │

└──────────────┘                     │  IFC (contact/admittance)│
                                     │  SRC (RTC/VLASH/OCP) │  │
                                     │  SAEC (step MDP)     │  │
                                     │  SMG (stereo/6D)     │  │
                                     │  SSG/PGL/OPT/ICR/SVL │  │
                                     └──────────────────────┘  │
                                                 │              │
                                                 └──────────────┘
```

**单 checkpoint 说明**：云端主干 + 边缘头 + 谓词头/接触头都是同一个模型文件的组件；没有按任务切换的权重；ICR 是非参数检索，SAEC/IFC 是确定性控制层。这样满足「所有任务同一模型、不得混用多个模型」的规则（[S2]）。

### 3.2 DR-VLA：双速率云边

**动机**：N 端口并发、远程延迟、观测过期。6B 模型每步同步前向在单 GPU 上很难支撑 N 个端口；但完全不用大模型又会丢语义。把「慢语义」和「快修正」拆开。

**结构**：

- **云端慢脑**：WLA-1.0 的 ER-1/VLM 主干（4B）+ 可选 MMDiT 的中间层特征；输出 `z_slow`（任务/场景/步骤语义，维度 1024–4096）。更新频率低（每 4–8 个 chunk，或场景显著变化时），异步执行。
- **边缘快脑**：每端口一个小型视觉编码器（ViT-S/14 或 ResNet-18，20–80M）+ 本体编码 + 对 `z_slow` 的 cross-attention + 动作头（flow matching 或回归），输出 `H×D` 的 chunk（H=4–16，D=14–16）。每步用最新观测。
- **残差**：边缘头预测「相对慢脑先验的残差」或直接预测动作；若直接预测，`z_slow` 作为 context token；若残差，`a = a_slow + Δa_edge`。推荐直接预测 + `z_slow` context，训练更稳。
- **健康标志**：`z_slow` 带时间戳/场景哈希/置信度；若过期超过阈值（如 500ms）或场景变化检测触发，则回退到全模型同步或上一帧特征 + 边缘修正。

**训练**：

```text
for each episode, t:
    d ~ Uniform(0, D_max)                 # 模拟延迟
    z_slow = Cloud(o_{t-d})               # 慢脑看旧帧
    a_hat  = Edge(o_t, z_slow)            # 快脑看新帧
    L = L_flow(a_hat, a_t) + λ L_cons(a_hat, Full(o_t))
```

`L_cons` 可选（需要全模型前向）；`L_flow` 是主损失。Cloud 可冻结或 LoRA；Edge 全量训练。为了让边缘头学会「忽略过期语义、相信当前观测」，延迟 d 要覆盖 0–40 步（CloudEdgeVLA 的设置，[S22]）。

**推理**：

- 云端在后台线程/进程跑，特征写入 per-port 缓存；边缘路径只读缓存，不阻塞。
- 若缓存为空（episode 开始），先用全模型同步出第一块，或用一个默认 `z_slow`（任务文本 embedding）启动。
- N 端口：云端动态批处理（收集多个 port 的请求，凑 batch）；边缘头共享权重、独立状态；每个 port 有独立 SSG/SAEC/IFC 状态。

**证据**：CloudEdgeVLA（[S22]）在 40 步延迟下保留 63.8–78.0% 成功率，VLASH 6.4%、单路径基线 3.0%；VLA-ULAP（[S23]）云端 284ms vs 边缘 20ms；RTC（[S15]）/VLASH（[S17]）证明异步/前滚可行。**[推断]** 这些结果可迁移到 UniBot，但需要在自己的服务上复现延迟曲线。

**消融**：无边缘头（全模型每步）、无云端（边缘 only）、fresh vs stale 训练、延迟 0/20/40/80/160ms、N=1/2/4/8。

**风险**：边缘头欠拟合（容量/数据不够）；`z_slow` 过期导致语义错；评测延迟未知；单模型审计。**回退**：全模型同步 + RTC。

### 3.3 SRC：推测式滚动分块

**动机**：评测端按 chunk 执行；远程调用有延迟；chunk 边界不连续会导致急停/抖动；接触任务对时差敏感。

**算法**（每个 `get_action`）：

1. **读状态**：最新观测 `o_t`、已执行/已承诺的动作前缀 `a_exec[0:k]`、上一块 `a_prev`。
2. **前滚**（VLASH，[S17]）：用 `a_prev` 把机器人状态从上一观测时刻前滚到 `t+Δ`（Δ=网络+推理延迟），得到预测状态 `ŝ_{t+Δ}`；用 `ŝ` 而不是 `o_t` 作为条件（或两者拼接）。
3. **生成**：边缘头/RTC 动作专家以 `ŝ` + `z_slow` + `a_exec[0:k]` 为条件，生成新块 `a_new`。训练时随机前缀长度 `k`，让模型学会「接着已执行的前缀继续」（RTC，[S15]；training-time RTC，[S16]）。
4. **自适应长度**（AAC，[S18]）：根据动作熵/接触分数选择 `H`：自由空间 H=16，接触/高熵 H=4–8；避免在接触阶段承诺太长的块。
5. **OCP 融合**：解一个小 QP，保留已承诺前缀，最小化与 `a_new` 的偏差 + 速度/加速度惩罚：

```text
min_a  ||a - a_new||² + λ1||D a||² + λ2||D² a||²
s.t.   a[0:k] = a_exec[0:k]
       |D a| ≤ v_max, |D² a| ≤ a_max
       joint limits / table keep-out (linearized)
```

6. **返回**：`a_cmd` 的前 `H` 步；缓存为 `a_prev`。

**延迟模型**：

```text
T_step = 控制周期（未知，暂按 33ms）
τ_edge = 边缘头前向 + 后处理（目标 < 30ms）
τ_net  = 网络往返（未知，按 20–80ms 估）
τ_cloud = 云端特征（异步，目标 < 300ms，不阻塞）
H·T_step ≥ τ_edge + τ_net + margin   # 同步模式的 chunk 覆盖
```

若评测是异步（新请求在旧 chunk 执行完之前到达），RTC 前缀 + OCP 融合就是必须的；若是同步，chunk 只要够长即可，但 OCP 仍能减小边界抖动。**[未核实]** 评测端是哪种。

**伪代码**：

```python
def get_action(port, obs):
    st = edge.encode(obs)
    z, age = cloud_cache[port].latest()
    if age > 500 or scene_changed(obs):
        z = cloud.fallback(obs)          # 同步兜底
    step, conf = ssg.classify(obs.language, st, scene)
    ctx = icr.query(st, step, scene, cache[port])
    s_roll = vlash.roll(obs, a_prev[port], delay_est)
    a_new, entropy = edge.act(s_roll, z, ctx, scene)
    H = aac.length(entropy, contact_score, step)
    a_new = a_new[:H]
    contact = ifc.estimate(obs, a_new[0])
    a_new = ifc.admittance(a_new, contact, step)
    a_cmd = ocp.blend(a_exec[port], a_new, v_max, a_max)
    a_cmd = saec.select(step, conf, contact, obs.time, a_cmd)
    a_cmd = compliance.clip(a_cmd, obs)
    a_prev[port] = a_cmd
    return a_cmd
```

**证据**：RTC（[S15]）、training-time RTC（[S16]）、VLASH（[S17]）、AAC（[S18]）、VLA-RAIL（[S19]）、DynamicVLA（[S20]）、FASTER（[S21]）。

**风险**：评测端可能不支持异步；chunk size 可能被固定；前滚模型误差；QP 求解时间；动作分布漂移。**回退**：同步 + 固定 chunk + 线性插值。

### 3.4 IFC：隐式力控

**动机**：API 没有 F/T/力矩；插入/拔出/闭合/放置是接触密集；位置控制器在接触时会被顶住。

**接触估计器**：

```text
e_track = || EE_obs(t+1) - EE_cmd(t) ||_Σ     # 位置跟踪误差（接触/受阻）
g_stall = 1[夹爪闭合指令下开度变化 < ε]        # 夹住/顶住
v_obj   = 腕部光流中物体相对 EE 的运动           # 物体是否跟随
c_t     = σ(w1 e_track + w2 g_stall + w3 v_obj + b)
```

`e_track` 是最接近力的代理：`F ≈ K_joint · e_track`（小位移线性近似）。在实验室用外部力传感器标定 `K` 和阈值（G1 + Dex1，200–500 个接触样本），得到 `c_t` 的校准。`c_t` 不是「力」，而是「接触概率/相对受阻程度」，足以驱动导纳和原语。

**导纳**：

```text
x_cmd[t] = α x_cmd[t-1] + (1-α) x_ref[t] - β c_t · n_t
```

`n_t` 是估计的接触法向（从 `e_track` 方向或物体表面法向）；自由空间 `β≈0`、高刚度；接触阶段 `β>0`、低刚度；修正限幅 ±2cm，防止振荡。也可用二阶 `M ẍ + D ẋ + K(x-x_ref) = -F_est` 的离散形式。

**原语**（按 SSG 步骤相位触发）：

| 原语 | 触发 | 动作 | 退出条件 |
|---|---|---|---|
| 插入搜索 | T10/T26/T13 | 平面螺旋（半径 0.5–2mm，1–2 圈）+ 微进给（0.5mm/步） | `c_t` 下降 + 物体/接头位移 |
| 拔出摆动 | T05/T11/T30 | ±2mm 摆动 1–2Hz + 后撤 1–2cm + 身体后撤 | 物体位移 > 阈值 |
| 拉链牵拉 | T19/T23/T31 | 夹住拉链头 + 低刚度沿缝牵拉 + 横向微摆 | 拉链头位移/谓词 |
| 倾倒 | T14/T32 | 倾斜 10–20° + 停顿 + 轻敲 | 药丸/水流出 |
| 放置 | T27/T21/T07 | OPT 位姿 + 低刚度下降 + 接触检测 + 缓放 + 静置 | 稳定性谓词 |

**身体力源（WBCL）**：`action.pivot`（vx/vy/angle_z/height）和 `action.lower_body`（15 维）可用。拔网线/电池时，手臂保持 + 身体后撤 2–5cm，产生比手臂更大的行程和更可控的拉力；插入时用腰部高度微调。数据集包含这些动作，模型可学；这是人形相对固定臂的独特自由度。

**实验室力蒸馏**（条件性）：若规则允许外部数据，用 Dex3-1 触觉/力反馈的 G1 采集 3–5 个接触任务（T10/T05/T19/T27/T14），训练 force-aware teacher；再把触觉 token 通过辅助损失蒸馏进 Dex1 学生（HapticVLA，[S25]）。若规则不允许，则只用于实验室分析/评测，不进入训练。

**证据**：FR-VLA（[S24]）隐式力推理；HapticVLA（[S25]）训练时触觉、推理时无触觉；TacVLA（[S26]）、FAWAM（[S27]）、Opt2VLA（[S28]）、ForceVLA（[S29]）、FM-VLA（[S30]）；无传感器力估计（[S31]）。

**风险**：无真实力反馈；接触估计噪声；原语任务相关；安全；外部数据规则；Dex3→Dex1 具身差异。**回退**：只用导纳 + 缓放，不依赖力蒸馏。

### 3.5 SAEC：分数感知 Episode 控制

**动机**：180 秒；成功优先；步骤可分；人为干扰会撤销步骤；重试/回滚需要预算。

**MDP**：

```text
状态: (task_id, step k, τ_remaining, predicate_confidence, retry_count, disturbance_flag)
动作: advance / retry / regrasp / rollback / abort
转移: advance → k+1 if predicate confirmed, else stay + penalty
      retry → k, retry_count+1, τ - c_k
      regrasp → k, reset grasp, τ - c_g
      rollback → k-1, τ - c_r
      abort → terminal, failure
奖励: +1 success; 0 failure; +P_step for tie-break; -λτ time
```

**策略**：用离线估计的 `p_k`（每次尝试成功率）和 `c_k`（耗时）解有限时域 DP；或用手写阈值：

```text
if predicate_conf > 0.8: advance
elif τ < τ_reserve: best_effort (highest-value remaining step)
elif contact and k in contact_steps: retry_with_primitive
elif disturbance_detected: rollback
elif retry_count < 3: retry
else: regrasp or advance_with_risk
```

**时间预算**：预留 10–15s 给终局步骤 + 释放/静置；`τ_reserve` 按任务难度设（Hard 多留）。超时是失败，但步骤分照算，所以「保步骤分」在最后 10s 仍有意义（同分裁决）。

**证据**：规则（[S2]）；SSG 步骤图（[S35]）；无需新模型。

**风险**：`p_k/c_k` 估计噪声；重试成本可能高于收益；谓词错误；人为干扰不可恢复。**回退**：固定重试 1 次 + 时间 guard。

### 3.6 SMG：立体度量 grounding

**动机**：空间 grounding 是 OOD 主因之一；透明物体（杯/试管/瓶）和薄物体（网线/拉链/图钉）对 2D 策略很难；3D 位姿能让 PGL/OPT/IFC 更准。

**步骤**：

1. **标定**：用 G1 URDF/官方安装尺寸近似；实验室棋盘格标定内参/外参；用已知尺寸物体验证。若都不可行，用 foundation stereo（如 FoundationStereo/StereoAnywhere）+ 已知 baseline 60mm 做度量尺度，或用单目深度 + 机器人几何尺度兜底。
2. **深度**：对 `cam_left_high/right_high` 做 rectify + stereo matching；输出度量深度；对透明/反光物体用多视角/深度补全/边缘先验。
3. **6D 位姿**：对已知类别用 FoundationPose/Any6D；对未见物体用类别无关分割 + 几何拟合（抓取点/容器开口/支撑面）。
4. **GFG（Geometry-First Grasp）**：从点云/网格采样抓取；用 antipodal/力闭合评分；选无碰撞、可达、接近方向的抓取；对 deformable（毛巾/包/拉链）用关键点/affordance，不用网格。
5. **接口**：把物体/容器 3D 位姿、支撑面、开口平面喂给 PGL/OPT/ICR；把接触距离喂给 IFC。

**证据**：Spa-Bench（[S32]）空间推理；AnySlot（[S33]）槽位级操作；SpaceVLA（[S34]）空间 VLA；G1+ 双目（[S13]）。

**风险**：无标定；透明/反光；深度噪声；算力；sim-real。**回退**：2D + 几何先验 + 机器人本体尺度。

### 3.8 合规层

- **单模型**：一个 checkpoint；边缘头/谓词头/接触头是组件；无任务特定权重；ICR 是非参数；SAEC/IFC 是控制逻辑。保留模型卡说明。
- **不自部署到机器人**：策略只在我们的服务器；评测端通过 API 调用。
- **不发力指令**：动作只有位置；IFC 用位置目标 + 观测。
- **外部数据**：若规则禁止，L2L/蒸馏只用于分析；训练只用官方数据 + 官方预训练权重。
- **N 端口**：恰好 N 个；每端口独立 session/token；reset 清理状态；并发压测。
- **安全**：动作限幅；桌面 keep-out；接触异常时回退；不输出危险速度。

```python
def get_action(port, obs):
    s = session[port]
    st = edge[port].encode(obs)
    scene = smg.update(obs, s.task_id)
    z, age = cloud_cache[port].latest()

    a_cmd, mode = saec.select(step, conf, contact, obs.time, a_cmd)
```

### 4.3 SAEC 选择

```python
def select(step, conf, contact, t, a_cmd):
    if conf > 0.8:
        return a_cmd, "advance"
    if t > deadline - reserve(step):
        return best_effort(a_cmd), "best_effort"
    if contact > 0.6 and step in CONTACT_STEPS:

    if disturbance_detected():

    if retry_count(step) < 3:

    return regrasp_or_advance(a_cmd), "regrasp"
```

### 5.3 NRB 脚本

- 对每个任务，把 `human_1_note` / `human_4_note` 解析成 `(object, axis, delta, timing)`；如「杯子向后」→ 在第 1 步后把杯子沿 -y 平移 5cm。
- 用 2.5D 场景重建 + 物体分割 + 修补 + 重打光生成视频；保留原始动作/状态对齐。

### 5.4 ACP 反事实

## 6. 实验设计

### 6.1 离线

- 动作误差（MSE/DTW）、步骤分类准确率、接触 AUC、chunk 边界 jerk、延迟注入下的动作一致性。
- 数据：官方验证集 + NRB/ACP 合成；按任务/轴分层。

### 6.2 仿真

- 只做**选择性**仿真：T27 叠碗、T10 插头、T05 网线、T19 拉链；用简化几何 + 域随机化。
- 目的：验证 IFC/SAEC 的逻辑，不追求 sim-real 迁移；不作为主证据。

### 6.3 真机调试

- 官方不计分单任务调试（[S37]）；选 3 任务 × 2 轴：
  - T27 StackBowls（放置/接触/稳定性）+ 位置、human；
  - T10 PlugCharger（插入/对准）+ 位置、background；
  - T05 DisconnectEthernet（拔出/身体力源）+ human、unseen。
- 每任务每轴 3–5 次；记录步骤级成功/失败、耗时、接触、延迟。
- 用 SSG 估计 q_k；与离线预测对比；决定是否提交正式评测。

### 6.4 正式评测

- 320 trials；总体/每任务/每轴成功率；步骤分；时间；失败模式。
- 若允许，跑 2 次（不同时间）估计方差；否则用 bootstrap + 跨任务一致性。

### 6.5 消融

| 消融 | 变量 | 预期 |
|---|---|---|
| 基线 | WLA 微调 + 同步整块 | 参照 |
| +DR-VLA | 延迟 0/40/80ms | 延迟下 +5–10pp |
| +SRC | RTC/VLASH/OCP | jerk -30%，延迟下 +3–5pp |
| +IFC | 接触任务 | T10/T05/T19/T27 +10pp |
| +SAEC | 重试/时间 | 时间 -10%，成功 +2–3pp |
| +SMG | 3D/透明 | 放置/未见 +3–5pp |
| +NRB | human 轴 | +5pp |
| +ICR | 少样本/干扰 | +2–4pp |
| N 端口 | 1/4/8 | 延迟/吞吐 |
| chunk | 4/8/16/32 | 边界/反应 |

### 6.6 指标

- 主：总体成功率；次：步骤分；诊断：每轴/每任务成功率、时间、重试次数、接触成功率、jerk、p50/p95/p99 延迟、失败模式分布。
- 统计：bootstrap 95% CI；按任务配对比较；预注册主指标，避免多重比较。

### 6.7 Go/No-Go

| 检查 | 通过 | 失败动作 |
|---|---|---|
| 调试 T27/T10/T05 | 至少 2 个任务 ≥ 基线 +1 次/5 次 | 不上正式；先修 |
| 延迟 80ms | DR-VLA/SRC 掉点 <5pp | 砍 DR-VLA/SRC |
| 接触任务 | 至少 2 个 +10pp | 砍 IFC 原语，留导纳 |
| human 轴 | +5pp | 加强 NRB/恢复 |
| 时间 | 无超时 | 调 SAEC/chunk |
| 单模型审计 | 通过 | 重构成一个 checkpoint |

**收敛后的核心押注只有 3 个**：核心 1（远程执行层）= I1+I2；核心 2（接触）= I3；核心 3（预算/步骤）= I4。I5 是支撑件；I6–I16 是支撑/后备/数据件。

### I1 DR-VLA（核心 1a）

- **痛点**：N 端口并发；6B 每步同步不现实；远程观测过期；human 干扰需要快速反应。
- **与现有方法差异**：不是「N 份 6B」，也不是「机器人上跑小模型」；是「共享慢脑 + 每端口快脑 + 配对训练」的单 checkpoint 服务架构。CloudEdgeVLA 给了云边特征/头的证据，但没解决 N 端口/单模型/UniBot API；VLA-ULAP 给了延迟/能耗证据，但没解决接触。
- **可行性**：WLA 的 ER-1 特征可用；边缘头 20–80M；配对训练不需要新数据（用时间偏移构造）；服务侧可控。
- **资源**：8×H100 训练 2–3 周；1–2 人；边缘头 1 周实现；压测 1 周。
- **最小实验**：延迟注入 0/40/80ms；比较「全模型同步」「边缘 only」「DR-VLA」的成功率/jerk/p95。
- **风险**：边缘头容量不足；`z_slow` 过期；评测延迟未知；审计认为「两个模型」。**缓解**：同一 checkpoint；模型卡；消融；回退全模型同步。

### I2 SRC（核心 1b）

- **痛点**：chunk 边界急停/抖动；远程延迟；接触阶段需要短块。
- **差异**：RTC 解决「怎么接」；VLASH 解决「用什么状态接」；AAC 解决「块多长」；OCP 解决「接得顺不顺」。四者组合成推理外壳，不改评测端。
- **可行性**：服务侧实现；动作专家支持前缀条件；QP 毫秒级；无需新数据。
- **资源**：1–2 周；1 人；CPU/GPU。
- **最小实验**：固定延迟 80ms；测 jerk/边界误差/成功率；对比同步整块、RTC、RTC+OCP。
- **风险**：评测同步；chunk 固定；前滚误差；QP 慢。**缓解**：同步回退；固定 H；线性插值。

### I3 IFC（核心 2）

- **痛点**：无 F/T；插入/拔出/闭合/放置靠「盲推」；Dex1 内部力控不可控。
- **差异**：把「力」变成「接触概率 + 导纳 + 原语 + 身体力源」；用实验室力传感器校准，不用挑战数据带力；WBCL 是人形相对固定臂的独特自由度。
- **可行性**：确定性代码 + 小头；200–500 样本校准；Dex1 内部柔顺；数据集有 pivot/lower_body。
- **资源**：1–2 周；实验室 G1/Dex1 + 力传感器；1 人。
- **最小实验**：T10 插入、T05 拔出、T19 拉链；对比无 IFC/导纳/导纳+原语+WBCL。
- **风险**：接触估计噪声；原语任务相关；安全；外部数据。**缓解**：限幅；只对接触步骤启用；人工监督；规则审查。

### I4 SAEC（核心 3）

- **痛点**：180s；成功优先；重试/回滚无预算；human 撤销。
- **差异**：把评分规则直接编码成 MDP；用 SSG 的 q_k 做 DP；不是「模型自己决定」，而是「规则感知的控制层」。
- **可行性**：确定性；调试估计 p/c；无需训练。
- **资源**：1 周；1 人；调试数据。
- **最小实验**：T27/T10/T05；对比「固定重试 1 次」「无重试」「SAEC」的时间/成功率。
- **风险**：p/c 噪声；重试成本；谓词错误。**缓解**：保守阈值；时间 guard；人工审查。

### I5 SMG（支撑）

- **痛点**：空间 grounding；透明/薄物体；放置/插入需要 3D。
- **差异**：用头部双目（60mm）做度量深度；容器系 6D；GFG；透明兜底；不是「再加一个深度相机」，而是「用已有双目 + 机器人几何」。
- **可行性**：G1+ 双目；数据集有 stereo；标定可做；foundation stereo/pose 可用。
- **资源**：1–2 周；标定；1 人；GPU。
- **最小实验**：T01 挂杯、T27 叠碗、T10 插头；对比 2D/深度/6D；测放置误差。
- **风险**：无标定；透明；深度噪声；算力。**缓解**：URDF 近似；多视角；2D 回退。

### 8.2 规则风险

- **单模型**：必须一个 checkpoint；边缘头/谓词头是组件；ICR 非参数；SAEC/IFC 控制逻辑。提交前做模型卡/审计。

- **合成数据**：NRB/ACP 基于官方数据生成，不引入外部演示；若规则禁止合成/增强，则退回真实数据 + 颜色/噪声/裁剪等轻量增强。
- **调试通道**：次数/成本未知；不把它当无限反馈；每次调试前定假设/指标。
- **安全**：动作限幅；不输出危险速度；接触异常回退；遵守评测现场安全。

### 8.3 回退顺序

1. 砍 I16 Critic（收益不确定）。
2. 砍 I11 L2L/蒸馏（规则风险）。
3. 砍 I5 SMG（无标定则回退 2D）。
4. 砍 I3 IFC 原语（留导纳）。
5. 砍 I1 DR-VLA（回退全模型同步 + RTC）。
6. 保底：WLA-1.0 微调 + RTC + SSG/SAEC + NRB。

## 11. 开放问题

1. **评测是同步还是异步？** `get_action` 是否在旧 chunk 执行完才调用？这决定 SRC 的收益。
2. **控制频率是多少？** 30fps？10Hz？这决定 chunk 长度和延迟预算。
3. **N 是多少？** 1/4/8？这决定 DR-VLA 的显存/吞吐设计。
4. **外部数据/预训练权重允许吗？** 手册 §2.3 之后不可见；必须问官方。
5. **调试通道次数/成本？** 决定 DebugLoop 的采样量。
6. **5 条英文复述都会用吗？** 语言分布决定 SSG/语言增强。
7. **human_1/human_4 备注是精确剧本吗？** 编号含义未解释；需官方确认。
8. **头部双目有标定吗？** 内参/外参是否随 API 提供？没有则需自标定。
9. **夹爪内部力限幅是多少？** 能否通过 API 设定？不能则只能靠位置柔顺。
10. **动作 chunk 是原样执行还是插值？** 决定 OCP 的必要性。
11. **reset 的初始位姿/场景是否固定？** 决定 ICR 预取和 SMG 标定。
12. **相机曝光/白平衡固定吗？** background 轴可能改光照。
13. **正式评测跑几次？** 一次还是多次？决定统计策略。
14. **超时/无效动作的步骤分怎么算？** 规则说超时失败、步骤分照算，但细节未明。
15. **`state_d435` 会通过 API 提供吗？** 如果提供，SMG 可用现成深度；否则只能用双目。
