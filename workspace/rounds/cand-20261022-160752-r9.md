# 想法区 · 从 X-DUB/FC* 到 X-DUB/PC*

**灵感词**：np-completeness / 最优子结构 / 线性规划  
**起点**：v0.9「X-DUB/FC*」。它的判决是：`FBP` 是 `PACK` 的松弛，严格间隙实例必然存在；50/50 的闭合依赖"临界层 LP 恰好不可行"这一经验事实，一旦撞上间隙，短证书消失，DEC 退回指数搜索。本轮不推翻 v0.9，也不急着去找那个间隙。本轮先问一个更靠前的问题：

> **`PACK` 的"指数"，到底指数在哪个参数上？**

v0.8 说 m≥3 时 `PACK` 是 `O(m^n)`。这句话是对的，但它描述的是**分支算法**，不是**问题**。m 是机器数，是问题参数；如果 m 固定（本轮基准 m=2/3），容量层可以写成一张状态表：

```text
状态 = 剩余容量画像 r = (r_1, …, r_m)
把任务 i 放到机器 k：  r_k ← r_k − p_i
```

状态总数是"把 ≤mH 拆成 ≤m 个部分的划分数"，对固定 m 是 `O(H^{m−1})`。**指数从 n 搬到了 m**。而 3-partition 的 NP 完全性恰恰是把 m 当输入：给定 3m 个数、m 个容量 B 的箱子，问能否每箱三个数、和恰为 B。m 固定时它是多项式（n^m 种分组，或 H^{m−1} 张画像）；m 增长时它才是强 NP 完全的。所以 **np-completeness 在本轮的正确用法不是"问题很难"，而是"难在哪个参数"**：v0.8/v0.9 的指数搜索，是在一个 m 被固定的问题上，用了对 m 指数的算法。

## 一句话直觉：证书不是"搜索的痕迹"，而是"状态表的一层"

如果决策过程是确定性的状态转移，那么 NO 的证书不需要是一棵搜索树（要检查分支覆盖、机器身份、跳过分支），而可以是**逐层的状态表**：第 i 层就是"放完前 i 个任务后所有可能的剩余容量画像"。检查器从初始画像出发，逐层重算后继、比对表；表在某一层为空，就证明 NO。它不回溯、不解 LP、不做浮点运算、不信任 provider 的任何中间结论。

这把 v0.9 的 `PACK(trace)`（Θ(搜索)，且要检查分支覆盖）换成 `PROFILE(layers)`（Θ(表长)，逐层确定）。代价是表长是伪多项式的：`O(n·H^{m−1})` 个数。**"短"和"可检查"第一次被分开**：LP 的 `n` 个有理数仍然是最短的；状态表是永远存在的那一个。

## 三个手算：为什么"m 固定"改变了问题的形状

### 手算 1：v0.9 的开篇例子，状态表只有 6 行

`p=(4,4,4,4,3,1)`，`m=2`，`H=10`（v0.9 用来解释 DFF 反例的那个实例）：

```text
L0: (10,10)
L1: (10,6)
L2: (6,6), (10,2)
L3: (6,2)
L4: (2,2)
L5: ∅          ← 空层 = NO
```

6 个状态、5 层，最后为空。同一实例：v0.8 的 m=2 bitset 要扫一遍子集和；v0.9 的 LP 给 `τ*=2.5` 与 6 个权重。三者都对，但**只有状态表是"逐层可复算"的**：第 3 层的 `(6,2)` 是"两个 4 分别放进两台机器（各剩 6），再把第三个 4 放进其中一台（剩 2）"；检查器不需要知道这条路径，它只需要验证 `L_{i+1}=succ(L_i)`。表本身既是算法的执行记录，也是证书。

### 手算 2：m=2 的分数墙就是整数墙（定理，不再是经验）

v0.9 在 30/30 个 PART2 上看到 `L_FBP=L_PACK`，把它当成"临界层的巧合"。其实 m=2 时可以证。设总分 `P>H`，反设 LP 可行但不存在子集 `T` 满足 `P−H≤p(T)≤H`（这正是 2-bin 整数可行）。那么每个可行配置 `S`（`p(S)≤H`）都满足 `p(S)<P−H`，即补集 `p(R\S)>H`。对任一 LP 解 `y` 求和：

```text
P ≤ Σ_S y_S p(S) ≤ H Σ y
Σ_S y_S (P−p(S)) > H Σ y
左边 = P Σy − Σ_S y_S p(S) ≤ P(Σy−1)
⇒ H Σy < P(Σy−1) ≤ H Σy (Σy−1)
⇒ Σy > 2,
```

与 `Σy≤2` 矛盾。所以 **`FBP(σ,H)` 可行 ⟺ `PACK(σ,H)` 可行（m=2、统一容量、无资格限制）**。这个证明只用了"补集仍是可行配置"这一向下封闭性。m=3 时最后一步只给 `Σy>2`，不够 `>3`，证明断了——**分数墙恰好停在两台机器**。

这也把 v0.9 的"间隙必然存在"逼到了正确的位置：如果所有 m 都相等，配置 LP 就会在一元工时下多项式时间判定 bin packing（分离是背包 DP），与 P≠NP 矛盾。所以间隙存在，但它是**大 m 现象**；我们的 m=2/3 基准在安全侧。本轮用画像 DP 在 m=3–8 上又搜了 2 万多个直接实例，一个间隙也没撞到，这与"间隙在大 m"一致。

### 手算 3：B&B 在 n=12 上只走 203 个节点，但 n=200 上不可用

PART2 的 30 个实例在 `H=OPT−1` 上，逐任务赋值 DFS（对照实现）中位 203、最大 624 个节点；画像 DP 中位 26、最大 49 个状态。n≤12 时两者都很快，B&B 甚至常数更小。但 n=200、m=3、H=200 时，画像 DP 是 516,156 个状态（含所有层）/0.86 s，而 B&B 是 `3^200`。**这不是常数之争，是参数之争。**

## 三个灵感词怎么落到算法上

### np-completeness：把难度归位到 m

三个事实拼起来：

1. 固定 m、工时一元：画像 DP 有 `O(H^{m−1})` 个状态/层，`O(n·H^{m−1})` 时间；所以 `PACK ∈ P`（对一元工时是多项式，对二进制工时是伪多项式）。
2. m 是输入：3-partition 直接归约到 `PACK`（m 个容量 B 的箱子、3m 个数），所以 `PACK` 是 NP 完全的。
3. 若 `PACK=NO` 有多项式长度的证书，则 `PACK ∈ coNP`，而 `PACK` 是 NP 完全的，于是 `NP=coNP`。

所以 **"NO 没有短证书"不是容量层的内禀性质，而是 m 增长时的性质**。v0.9 把这条 coNP 壁垒误用在了 m=2/3 的基准上；在固定 m 下，状态表就是那个多项式（伪多项式）证书。本轮把这条边界明确写出来——它不是坏消息，它告诉我们：**该修的是最后的算法层，不是再找一个更强的松弛**。

### 最优子结构：Bellman 方程就是算法

固定任务顺序后，"放完前 i 个任务、剩余画像 r"就是子问题，且后续只依赖 `r`，不依赖具体谁在哪台机器上：

```text
V_i(r) = OR_{k ∈ E_i, r_k ≥ p_i} V_{i+1}(r − p_i e_k)
```

这不是一个新界，而是把 v0.8 的"从根往下枚举 `(i,k)`"改写成"按层收集所有可能的 `r`"。**最优子结构在这里的作用是消灭重复子问题**：同一层里两个不同的部分赋值只要诱导同一个 `r`，就合并。v0.8 的 DEC 里，`(R,A,est)` 的记忆化也是这个思想，但它记的是"任务集合 + 机器可用时间"，粒度太细；画像 DP 记的是"剩余容量向量"，粒度正好。

### 线性规划：从"最后一道墙"降为"最短见证"

LP 不删。`WEIGHT(w)` 仍然是 n 个有理数的短见证，仍然值得在 DEC 的每个节点先跑。但它不再是"闭合的最后一层"：它只在 LP 不可行时存在。v1.0 的层次是

```text
max(L0, L_DFF) ≤ max(L0, L_FBP) ≤ max(L0, L_PACK) = max(L0, L_PROFILE) ≤ OPT
```

注意最后是 **等号**：`PROFILE` 不更强，它只是把同一个 `L_PACK` 从"搜索"改成"表"。这也顺手回答了一个实现问题：v0.9 的 `frac_pack` 解的是等式形式（`Σy=1`），而定义是覆盖形式（`Σy≥1`）；本轮证明两者在向下封闭的配置族上**同值**（对偶最优可取非负），所以 v0.9 的数值实验没有系统性偏差。

## 本轮的动作：只换最后一层，不删任何开关

新增三样：

1. **`PROFILE(σ,H)`**：容量层的精确判定，状态 = 剩余容量画像；输出逐层状态表。它替换 v0.8 的 `PACK`，判定结果逐字相同（80/80 实测），但算法从 `O(m^n)` 变成 `O(n·H^{m−1})`。
2. **`PROFILE-OPT`**：不二分 H，直接在负载画像上跑一遍，返回精确的 `L_PACK`；纯分箱 50/50 与独立 OPT 相等。
3. **`CHECK-PROFILE`**：逐层比对状态表的检查器。接受 ⇒ 该节点 `PACK=NO`；不接受就拒绝。它不检查分支覆盖，因为根本没有分支。

v0.9 的 `FBP-LB`、`WEIGHT`、`CHECK`、v0.8 的 `DEC`、`CBJ`、`FT-PORT` 全部保留：

```text
关闭 PROFILE + PROFILE-OPT   → v0.9 的 X-DUB/FC*
只开 PROFILE 叶              → v0.9 搜索 + 可检查的精确容量节点
全部打开                     → v1.0 的 X-DUB/PC*
```

## 2. 诊断：指数在 m，不在 n

v0.8/v0.9 把容量层的代价记成 `O(m^n)` 或"m≥3 时指数 B&B"。这句话作为**分支算法**的界是对的，但它把参数搞混了：

- 输入规模是 `n` 与 `log(max p_i)`；`m` 是机器数，是问题参数。
- 分支算法按任务逐个枚举机器：`m^n`，对 n 指数。
- 但容量层的状态只需记住"每台机器还剩多少容量"：`r∈N^m`，`Σr_k = mH − Σ_{已放} p_i`。同一层里所有状态的**总和相同**，所以状态数不超过"把该总和拆成 ≤m 个部分"的划分数：

```text
|L_i| ≤ p(S_i, m) ≤ S_i^{m−1} / (m! (m−1)!),   S_i ≤ mH.
```

固定 m 时这是 `O(H^{m−1})`，与 n 无关（只随层数线性增长）。

这就是本轮的起点：**v0.8 的指数搜索，是在一个 m 被固定的问题上，用了对 m 指数的算法。** 而 3-partition 的 NP 完全性要求 m 是输入的一部分：给定 3m 个数、m 个容量 B 的箱子，问能否每箱三个数、和恰为 B。m 固定时，暴力枚举只有 `n^{O(m)}` 种分组，或 `O(H^{m−1})` 张画像；m 增长时才是强 NP 完全的。

## 3. 画像 DP

### 3.1 容量层的形式定义

**定义 1（PACK）**：给定 `σ=(R,A,est,q)` 与 `H`，`PACK(σ,H)` 为真当且仅当存在赋值 `α:R→[m]`，使得

```text
(A1)  ∀i∈R:  α(i) ∈ E_i(σ,H) = {k : max(A_k,est_i)+p_i+q_i ≤ H}
(A2)  ∀k:    Σ_{i: α(i)=k} p_i ≤ H − A_k.
```

这与 v0.8 的 `PACK` 完全相同；v0.9 的 `FBP` 是它的配置 LP 松弛。

**定义 2（画像状态）**：初始容量 `C=(H−A_1,…,H−A_m)`。放完前 i 个任务后的画像是

```text
r = C − Σ_{j≤i} p_{π(j)} e_{α(π(j))}.
```

`canon_σ(r)` 在每个"`A_k` 相同"的机器块内把分量降序排列；块间不排（不同 A 的资格集不同，不能互换）。

**定义 3（层）**：

```text
L_0 = { canon_σ(C) }
L_{i+1} = { canon_σ(r − p_{π(i+1)} e_k) :
           r∈L_i,  k∈E_{π(i+1)},  r_k ≥ p_{π(i+1)} }.
```

### 3.2 精确性

**定理 1（画像 DP 精确）**：`PACK(σ,H)` 为真 ⟺ `L_n ≠ ∅`。

**证明**：对 i 归纳证明更强的命题：`L_i` 恰为"把前 i 个任务按某个合法赋值放到机器上"所能得到的所有规范画像之集。

- i=0：只有空赋值，画像是 `canon(C)`。
- 归纳步：任一 i+1 步赋值 = 前 i 步赋值 + 把任务 `π(i+1)` 放到某台 `k∈E_{π(i+1)}` 且 `r_k≥p_{π(i+1)}` 的机器。由归纳假设，前 i 步的画像在 `L_i` 中；转移枚举了所有这样的 k，故得到所有 i+1 步画像。反过来，`L_{i+1}` 的每个元素都由 `L_i` 的某个画像加一个合法 k 得到，对应一个合法赋值。
- `canon_σ` 只置换同一等 A 块内的机器；这些机器的 `A_k` 相同，故 `E_i` 相同、容量相同，置换保持合法性；且 `canon_σ` 是块内置换群上的幂等映射，不丢状态。

n 步后 `L_n≠∅` 当且仅当存在合法赋值。证毕。

**推论 1**：`L_PROFILE(σ)=L_PACK(σ)`，对每个 σ 成立。v1.0 没有变强，只是换了算法与证书。

### 3.3 算法

```text
PROFILE(σ,H):
 1  C[k] ← H − A[k];  if ∃k: C[k] < 0: return NO(∅)
 2  for i∈R:  E[i] ← {k : max(A[k],est[i]) + p[i] + q[i] ≤ H}
 3  if ∃i∈R: E[i]=∅: return NO(∅)
 4  blocks ← 把 {k : A[k] 相同} 分块，块内下标连续
 5  π ← R 按 (−p[i], i) 排序
 6  cur ← { canon(C, blocks) };  layers ← [cur]
 7  for i in π:
 8      nxt ← ∅
 9      for r in cur:
10          for k in E[i]:
11              if r[k] ≥ p[i]:
12                  nxt ← nxt ∪ { canon(r − p[i]·e_k, blocks) }
13      layers.append(nxt);  cur ← nxt
14      if cur = ∅: return NO(layers)
15  return YES(layers)
```

要点：

- **任务顺序任意**都正确；按 `p` 降序只是让空层更早出现（大任务先放，失败得快）。
- **规范化只在等 A 块内做**；跨块排序会破坏资格集的对应关系，是错的。
- **强制任务**可选加速：若 `|E[i]|=1` 且唯一机器容量够，直接赋值，不分支（v0.8 的 `pack_feas` 已有此步）。它不改变正确性，只减少层宽。
- 空间只需保留当前层；要出证书才保留全部层。

### 3.4 状态表证书

**定义 4（状态表证书）**：`T=(L_0,…,L_k)` 是 `PROFILE(σ,H)` 的一次执行记录，要求 `L_0={canon(C)}`，且对每个 `i<k`，`L_{i+1}` 恰为 `L_i` 的全部规范后继；若 `L_k=∅`（或 `k=n` 且 `L_n≠∅`）则表结束。

```text
CHECK-PROFILE((σ,H), T):
 1  if T[0] ≠ {canon(C)}: reject
 2  for i = 0..k−1:
 3      nxt ← { canon(r − p[π(i)]·e_j) : r∈T[i], j∈E[π(i)], r[j] ≥ p[π(i)] }
 4      if T[i+1] ≠ nxt: reject
 5      if nxt = ∅: return accept iff i+1 = k
 6  return accept iff k = n and T[n] ≠ ∅
```

**定理 2（证书可靠且完备）**：

(a) 若 `CHECK-PROFILE` 接受 `T`，则 `T` 是 `PROFILE(σ,H)` 的精确执行记录，故 `L_n=∅ ⇔ PACK(σ,H)=NO`。  
(b) 若 `PROFILE(σ,H)` 返回 NO，它输出的 `layers` 被 `CHECK-PROFILE` 接受。

**证明**：(a) 检查器从唯一初始画像出发，逐层验证后继集完全相等；由定理 1 的归纳，`T[i]` 必等于真实第 i 层。表在空层结束即 `L_n=∅`。(b) 算法输出的正是这个逐层后继集，逐行相等。证毕。

**与 v0.9 的 `CHECK` 的差别**：

- `PACK(trace)` 要检查"每个内部结点的分支覆盖所有 `(i,k)`"——这依赖求解器记录的机器身份、`est` 重算、跳过分支的归一化，v0.9 §11.5 自己列为易错点。
- `PROFILE` 没有分支，检查器只做"逐层集合相等"。它不信任 provider 的搜索，只信任自己的重算。
- 代价：表长是 `O(Σ|L_i|·m)` 个整数，不再是 v0.9 的 `n` 个有理数。**证书从"短"变成"总是存在且无搜索"**。

### 3.5 `PROFILE-OPT`：单遍精确 `L_PACK`

不二分 H。直接在负载画像上 DP：

```text
PROFILE-OPT(σ0):                       # 根状态、统一容量
 1  U ← min(CP, LPT, MWKR)(σ0)         # 初始上界
 2  cur ← {(0,…,0)};  best ← U
 3  for i in π:
 4      nxt ← ∅
 5      for load in cur:
 6          for k in 0..m−1:
 7              t ← load + p[i]·e_k
 8              if max(t) ≤ best: nxt ← nxt ∪ { sort(t) }
 9      cur ← nxt;  if cur=∅: break
10  return min_{load∈cur} max(load)     # cur 为空则 best
```

**定理 3**：`PROFILE-OPT` 返回 `min_α max_k (A_k + Σ_{i:α(i)=k} p_i)`，即容量层的最优 makespan。证明同定理 1（状态是负载向量，枚举所有赋值），取 min-max。证毕。

对纯分箱根状态（`est=q=0`、无资格限制），这个值就是 `L_PACK=OPT`：§9.7 的 50/50 与独立精确解相等。若根状态有优先约束，忽略 `est/q` 只会让问题更容易，故它仍是 `L_PACK` 的一个**下界**（不一定相等），`PC-SOLVE` 第 4 行用它安全。

### 3.6 工程细节

- **等 A 分块**：DEC 节点上 `A` 可能互异；只对相同的 `A_k` 排序。块的数量最多 m，块内排序的代价可忽略。
- **强制单资格任务**：`|E[i]|=1` 时直接扣容量，不进层。这与 v0.8 `pack_feas` 的 forcing 一致。
- **下界剪枝（可选）**：每层算一次剩余总加工 `Σ_{i≥j} p` 与 `Σr`，若体积超出直接判空；O(1) 维护。
- **LP 先导**：DEC 节点先跑 `WEIGHT`，若 `τ*>m` 直接 NO（n 个数的短证书）；否则再跑 `PROFILE`。顺序可按 `n` 与 `H` 的估计切换，正确性不变。

## 4. 线性规划的角色

### 4.1 等式形式与覆盖形式同值

v0.9 的实现 `frac_pack` 解的是

```text
(P2)  min Σ_S y_S   s.t.  Σ_{S∋i} y_S = 1 (∀i),  y ≥ 0,
```

而定义是覆盖形式

```text
(P1)  min Σ_S y_S   s.t.  Σ_{S∋i} y_S ≥ 1 (∀i),  y ≥ 0.
```

`P2 ≥ P1`（P2 更受限）。但两者对偶的最优值相同：

**引理 4（等式=覆盖）**：设配置族 `F` 向下封闭（`S∈F, T⊆S ⇒ T∈F`）且每个单元素集 `{i}∈F`。则 `P1=P2`。

**证明**：`P1` 的对偶是 `D1: max Σw, w(S)≤1 ∀S∈F, w≥0`；`P2` 的对偶是 `D2: max Σw, w(S)≤1 ∀S∈F, w free`。`D2≥D1`。取 `D2` 的任一最优 `w`。若某 `w_i<0`：由于 `{i}∈F` 给 `w_i≤1`，且目标对 `w_i` 单调增，最优处 `i` 必属于某个紧约束 `S`（否则可把 `w_i` 略增，仍可行且更优）。于是 `w(S\{i}) = w(S) − w_i > 1`；而 `S\{i}⊆S∈F` 向下封闭，`S\{i}∈F`，违反约束（若 `S={i}`，则 `w(S)=w_i<0<1`，不紧，矛盾）。故 `w≥0`，`D2` 的最优值不超过 `D1`，两边相等。证毕。

**推论 2**：v0.9 的 `τ*` 数值与定义一致；§9.5 的间隙搜索没有"等式形式偏强"造成的假阴性。

### 4.2 m=2：分数墙就是整数墙

**定理 5（m=2 精确）**：两台同容量机器、无资格限制、总加工 `P>H`。则 `FBP(σ,H)` 可行 ⟺ `PACK(σ,H)` 可行。因此 `L_FBP=L_PACK`。

**证明**：`⇒` 平凡。`⇐` 反设 `FBP` 可行但 `PACK` 不可行。`PACK` 不可行等价于：不存在 `T⊆R` 使 `P−H ≤ p(T) ≤ H`（两箱中一箱的装载量必须落在这个区间）。于是每个可行配置 `S`（`p(S)≤H`）都满足 `p(S)<P−H`（它不能落在区间内），即 `p(R\S)>H`。

取任一 FBP 解 `y`。由覆盖：

```text
P = Σ_i p_i ≤ Σ_i p_i Σ_{S∋i} y_S = Σ_S y_S p(S) ≤ H Σ_S y_S.        (1)
```

由补集：

```text
Σ_S y_S (P − p(S)) > H Σ_S y_S.                                      (2)
```

左边 `= P Σ_S y_S − Σ_S y_S p(S) ≤ P Σ_S y_S − P = P(Σy−1)`，最后一步用 `Σ_S y_S p(S) ≥ P`。代入 (2)：

```text
H Σy < P(Σy − 1) ≤ H Σy (Σy − 1)      （用 (1) 的 P ≤ HΣy）
⇒ 1 < Σy − 1
⇒ Σy > 2,
```

与 FBP 的 `Σy≤2` 矛盾。证毕。

**注**：证明只用向下封闭性（补集仍是可行配置）。m=3 时最后一式只给 `Σy>2`，不够 `>3`，证明在此断裂；这不是技巧问题，§4.3 的实验显示 m≥3 确实找不到反例但也证不出。

### 4.3 间隙搜索

**问题**：是否存在 `(p,m,H)` 使 `PROFILE` 判 NO 而 `FBP` 可行（即 `L_FBP<L_PACK`）？

| 实验 | 规模 | 结果 |
|---|---|---|
| 直接随机搜索，m=3–5 | 19,272 个实例，448 个 PACK-NO | **0 个间隙** |
| 直接随机搜索，m=6–8 | 2,997 个实例，59 个 PACK-NO | **0 个间隙** |
| 穷举，m=3, H=10, n=8–9 | 268 个 PACK-NO | **0 个间隙** |
| m=2 穷举（定理 5 的数值核对） | 31,468 个实例 | **0 个反例** |

**为什么间隙一定存在（但不在小 m）**：若所有 m 上 `L_FBP=L_PACK`，则配置 LP 在一元工时下多项式时间判定 bin packing（分离是 `O(nH)` 背包 DP），与 P≠NP 矛盾。所以间隙存在，但它是**大 m 现象**；m=2 有定理，m=3–8 的 22,269 个随机实例没撞到。本轮**没有**给出具体构造，这是 §10.2 的边界。

## 5. 算法

### 5.1 `PC-DEC`：把 `PACK` 换成 `PROFILE`

在 v0.8 的 `(D1) 截止期 / (D2) 能量 / (D3) 阈值 memo` 与 v0.9 的 `(D5) WEIGHT` 之后：

```text
(D4') if not PROFILE(σ,H): return NO(PROFILE, layers)
```

`(D5)` 保留在 `(D4')` 之前：LP 不可行时用 `n` 个数的短证书；LP 可行时才建表。

```text
PC-DEC(σ=(R,A,est), H, memo):
  if R=∅: return YES([])
  if max(A)>H: return NO(DEAD, ⊥)
  est,q ← HEADS-TAILS(σ)
  if ∃i∈R: est_i+p_i+q_i>H: return NO(DEAD, (i,est_i))
  if E(R,A)>H: return NO(ENERGY, ⊥)
  key ← (R,A,est_R)
  if memo.bad[key] ≥ H: return NO(MEMO, key)

  if T_LP(σ):                                  # v0.9
      τ,w ← FBP-SOLVE(σ,H)
      if τ>m: memo.bad[key]←max(…,H); return NO(WEIGHT, w)

  if T_PROFILE(σ):                             # 本轮
      ok,layers ← PROFILE(σ,H)
      if not ok: memo.bad[key]←max(…,H); return NO(PROFILE, layers)

  for i in READY(R) sorted by (H−q_i−p_i)−est_i:
      for k in 0..m−1:
          t ← max(A_k, est_i)
          if t+p_i+q_i>H: continue
          A' ← A with A'_k=t+p_i
          est' ← PROPAGATE(est, i, t+p_i)
          r ← PC-DEC(R\{i}, A', H, memo)
          if r=YES: return YES([(i,k,t)]+r.sched)
  memo.bad[key]←max(…,H)
  return NO(RESOLVE, children)
```

`T_PROFILE(σ)` 的建议：根调用、`|R|≤κ_P`（默认 40）、或 `H≤H_P`（默认 200）。这三个阈值是工程建议，本轮未调参。超过时退回 v0.8 的 `PACK`/v0.9 的 `WEIGHT`，正确性不变。

### 5.2 `PC-SOLVE`

```text
PC-SOLVE(σ0)
1  U ← min(CP, LPT, MWKR)(σ0)
2  L ← max(L0(σ0), L_DFF(σ0))
3  if T_LP(σ0): L ← max(L, FBP-LB(σ0, L, U−1))
4  if T_PROFILE(σ0): L ← max(L, PROFILE-OPT(σ0))      # 无优先时 = L_PACK；有优先时是下界
5  if L ≥ U: return CERT(U, schedule(U), root-witness)
6  memo ← ∅
7  loop:
8      r ← PC-DEC(σ0, U−1, memo)
9      if r=NO(P): return CERT(U, schedule(U), P)
10     if r=YES(π):
11         U ← makespan(π); goto 2
12     if r=? : return v0.9-FALLBACK(σ0, U, L)
```

第 4 行是新的：`PROFILE-OPT` 把 `L_PACK` 从"二分 × B&B"变成"一遍 × 状态表"；有优先约束时它退化为纯容量下界，但仍可采纳。第 9 行返回的 `P` 里每个 `PROFILE` 叶都带表，`CHECK-PROFILE` 逐层可验。

**定理 6（`PC-SOLVE` 正确）**：若 `PC-SOLVE` 返回 `U`，则 `U=OPT(σ0)`。

**证明**：与 v0.9 定理 3 同构；唯一变化是第 4 行的 `L` 用 `PROFILE-OPT`，由定理 3 与推论 1 它等于 `L_PACK≤OPT`；第 9 行的 NO 由定理 2 与 `PC-DEC` 的完备性（只剪必要条件，(D4') 与 `PACK` 同判定）得不存在 `Cmax≤U−1` 的调度。夹逼得 `U=OPT`。证毕。

**终止性**：`U` 严格下降（整数），下界 `L` 单调不减，最多 `U0−L0+1` 轮。

## 6. `CHECK-PC`

### 6.1 证书语法

```text
CERT  ::= (U, π, P)
P     ::= LEAF(rule, witness) | RESOLVE(children)
rule  ::= DEAD(i,v) | ENERGY | DFF(t) | WEIGHT(w) | PROFILE(table) | MEMO(key)
table ::= (L_0, L_1, …, L_k)          # L_i ⊆ N^m 的规范画像集合
```

### 6.2 检查规则

| 规则 | 检查 | 代价 |
|---|---|---|
| `DEAD(i,v)` | 重算 `est_i`，确认 `est_i+p_i+q_i>H` 且 `v=est_i` | O(n) |
| `ENERGY` | `ceil((Σ_R p+ΣA)/m)>H` | O(n+m) |
| `DFF(t)` | `t·ceil(B_t/m)>H` | O(n) |
| `WEIGHT(w)` | `w≥0, Σw>m, ∀可行 S: w(S)≤1`（背包） | O(m·n·H) |
| `PROFILE(table)` | 逐层重算后继集，比对；空层 ⇒ NO；表必须在空层结束 | O(m·Σ|L_i|) |
| `MEMO(key)` | 确认 `key` 在同一证明中作为 `NO(·,H')`、`H'≥H` 出现 | O(1) |
| `RESOLVE` | 子结点恰为 `(i,k)` 的全部分支，逐个 VERIFY | 递归 |

**定理 7（`CHECK-PC` 可靠）**：若 `CHECK-PC(U,π,P)` 接受，则 `OPT(σ0)=U`。

**证明**：原始侧 `π` 是 `Cmax≤U` 的合法调度 ⇒ `OPT≤U`。对 `P` 归纳：每个 `LEAF` 规则分别是 v0.8/v0.9 的必要条件（`DEAD/ENERGY/DFF/WEIGHT`）或定理 2 的 `PROFILE`；`RESOLVE` 的分支覆盖所有 `(i,k)`，每个子结点 NO ⇒ 该状态 NO。故根 `NO(σ0,U−1)` ⇒ 不存在 `Cmax≤U−1` 的调度 ⇒ `OPT≥U`。夹逼。证毕。

**定理 8（根证书完备）**：若 `PC-SOLVE` 在第 5 行以 `L≥U` 返回，则 `(U,π,w)` 或 `(U,π,table)` 被接受。`PROFILE-OPT` 的最终负载画像给出 `L_PACK` 的见证；`L≥U` 意味着 `PROFILE(σ0,U−1)=NO`，表由定理 2(b) 接受。证毕。

## 8. 复杂度

### 8.1 画像 DP

```text
|L_i| ≤ p(S_i, m) = O(S_i^{m−1}) = O((mH)^{m−1})        （m 固定）
时间  O(n · m · max_i |L_i|) = O(n · m · (mH)^{m−1})
空间  O(max_i |L_i|)                     （不存全表）
证书  O(Σ_i |L_i| · m) 个整数
检查  O(Σ_i |L_i| · m) 次整数比较
```

m=2：`O(nH)` 状态·转移，与 v0.8 的 bitset 同阶（常数更差，元组哈希 vs 位运算）。m=3：`O(nH^2)`。m=4：`O(nH^3)`。

### 8.2 复杂度边界

**定理 9**：

(a) 固定 m、工时一元（`H` 以一元给出）：`PACK ∈ P`，`PROFILE` 的时间 `O(n·m·(mH)^{m−1})` 是输入规模的多项式。

(b) m 是输入的一部分：`PACK` 是 NP 完全的（3-partition 归约），且若 `PACK=NO` 有多项式长度的证书族，则 `NP=coNP`。

**证明**：(a) 由 §8.1 的状态数界。(b) 3-partition：给定 `3m` 个整数 `a_i∈(B/4,B/2)`、`Σa_i=mB`，问能否分成 m 个三元组、每组和 `B`。取 `p=a`、`H=B`、m 台机器，则 `PACK` 可行 ⟺ 存在这样的分组（每箱恰好 3 个，因为 4 个最小数之和 >B、2 个数之和 <B）。这是强 NP 完全的。YES 证书是赋值 α（多项式），故 `PACK∈NP`；若 NO 也有多项式证书，则 `PACK∈coNP`，由 NP 完全性 `NP⊆coNP`，即 `NP=coNP`。证毕。

**推论 3**：v0.8/v0.9 的"m≥3 指数"应读作"m 增长时指数"；在固定 m 的基准上，容量层从来不需要指数搜索。**短 NO 证书的壁垒同样只在 m 增长时出现**。

### 8.3 与 v0.8/v0.9 的对比

| 对象 | 最坏复杂度 | NO 证书 | 证书长度 |
|---|---|---|---|
| v0.8 `PACK` (m≥3) | `O(m^n)` | B&B 树 | Θ(搜索) |
| v0.9 `L_FBP` | 枚举 `O(2^n n^2 I)` / 列生成 poly | `w∈Q^n` | **n 个数** |
| v1.0 `PROFILE` | `O(n·m·(mH)^{m−1})` | 逐层画像表 | `O(Σ|L_i|·m)`，实测 ≤171 |
| v1.0 `PROFILE-OPT` | `O(n·(mU)^{m−1})` | 最终负载画像 | O(m) |
| v1.0 `PC-DEC` | 与 v0.8 同树，每节点 `O(nH^{m−1})` | 叶见证 + DAG | — |

| 族 | # | `L_PACK` 复现 | 状态数 中位/最大 | 时间 最大 | 赋值 DFS 节点 中位/最大† | v0.8 DEC 节点 中位/最大 |
|---|---:|---:|---:|---:|---:|---:|
| DENSE30 | 30 | 30/30 | 19 / 38 | 0.1 ms | 85 / 307 | 1 / 1,455 |
| PART2 | 30 | 30/30 | 26 / 49 | 0.1 ms | 203 / 624 | 7,683 / 17,109 |
| PART3 | 20 | 20/20 | 23 / 57 | 0.2 ms | 70 / 941 | 17,683 / 63,283 |

`L_PACK` 的复现是对全部 80 个实例做 `[L0,OPT]` 二分得到的（含 `est/q` 资格）；与 v0.8 存档的 `LPACK` 逐例相等。时间含二分（1–3 次 DP）。† 为公平对照而实现的逐任务赋值 DFS 的节点数；m=2 时 v0.8 实际走的是 `O(nH/word)` bitset，不是这个 DFS，故 m=2 一行只用于"搜索 vs 状态表"的量级对照，不代表 v0.8 的真实耗时。

**三个观察**：

1. 容量层本身在 n≤13 上并不贵（赋值 DFS 中位 203；m=2 的 bitset 更快），贵的是 v0.8 的 **DEC 调度搜索**（中位 7,683）。画像 DP 不能减少 DEC 节点；它减少的是每个节点的容量判定成本，并让 NO 可检查。
2. 状态数比 B&B 节点少 3–8×（26 vs 203；23 vs 70），但常数更差（元组哈希）；n≤13 时两者都在 0.2 ms 内，**真正的差别在 n 大时**（§9.3）。
3. DENSE30 的容量层只有 23 个 NO 节点（其余 7 个 `L_PACK<OPT`，是 v0.9 的优先/关键路径缺口）；画像 DP 对它们无能为力，符合"容量层不负责优先"的定位。

### 9.3 规模

固定随机分布 `p_i∈[1,⌊mH/n⌋]`，测“全部层状态和 / 时间”：

|---:|---|---:|---:|
| 2 | (10,40) | 111 | <0.1 ms |
| 2 | (200,200) | 10,443 | 12 ms |
| 3 | (50,100) | 40,040 | 64 ms |
| 3 | (200,200) | 516,156 | 0.86 s |

| 5 | (50,100) | 13,162,014 | **47.5 s** |
| 5 | (200,40) | 1,221,759 | 3.6 s |

方向是对的：n 从 10 到 200，状态只随层数线性增长；`H` 和 `m` 才是墙。m=5、H=100 已经不可接受——这是 §10.1 的边界。

## 10. 负结果与边界

1. **伪多项式，不是多项式**：`O(nH^{m−1})` 对 `H` 是指数的（m 固定时是多项式于一元 H，但对二进制 H 是伪多项式）。m=5、H=100 已 1300 万状态/47 秒；真实工时（H 上千）不可用。这是最大边界。
2. **间隙没有构造**：22,269 个随机 + 268 个穷举没找到 `L_FBP<L_PACK`，也没有证明 m≥3 时相等。计数论证只说"大 m 必有"，没说第一个 m* 在哪。m=2 有定理，m=3 没有。
3. **核是全局的**：κ 中位≈n；不要指望用核做小证书或局部解释。与 v0.9 的对偶支撑负结果一致。
4. **m=2 时 bitset 仍更快**：v0.8 的 `_pack2` 是 `O(nH/word)` 位运算，画像 DP 的元组哈希常数更大；v1.0 的收益在 m≥3 与"NO 可检查"，不在 m=2 的墙钟。
5. **DEC 树不变**：画像 DP 只换容量判定；DENSE30 的 7 个容量层缺口（优先/关键路径）一个都治不了。v1.0 的搜索节点数与 v0.8 相同。
6. **检查器 = 重算**：`CHECK-PROFILE` 的代价与求解相同，不是"短证明"；它买到的是"无搜索、无浮点、无分支覆盖"。在复杂度意义上，状态表不是短证书。
7. **表长随 m 指数增长**：证书数字个数 `O(Σ|L_i|·m)`，m=4/5 时可能比 LP 的 n 个数大几个数量级；只在 m≤3、H≤100 有明显优势。
8. **LP 仍是唯一的短见证**：`WEIGHT` 的 n 个有理数在 LP 不可行时仍是最短的；`PROFILE` 不能替代它，只能兜底。
9. **浮点/有理重构**：`WEIGHT` 路径仍依赖 v0.9 的 `limit_denominator`；本轮没有改。
10. **没有 n≥250、m≥6 大 H、真实 RCPSP、PSPLIB**：外推需谨慎。
11. **没有形式化验证**：定理 1/2 是纸面证明 + 随机对拍；检查器有 466 次篡改测试，但不是 Coq/Isabelle。

## 11. 已知风险

1. **m=5、H=100 的 47 秒**：这是硬边界。若目标实例的工时是几百到几千，画像表会先于搜索爆掉，`T_PROFILE` 只能关掉，退回 v0.9 的 LP + v0.8 的 B&B。
2. **`L_FBP=L_PACK` 在 m=3–8 上仍只是经验**：22,269 个随机实例不足以覆盖强 NP 难的构造；某个真实实例上 `L_FBP<L_PACK` 时，LP 短证书消失，只剩画像表。
3. **证书表不是短证书**：`CHECK-PROFILE` 与求解同代价；如果评审要求"多项式长度的见证"，v1.0 只对固定 m + 一元 H 成立（此时它确实是多项式长度），对二进制 H 不成立。
4. **画像 DP 的状态数对 m 指数**：m=4 已经 82 万状态（H=100），m=5 1300 万；`m>5` 基本不可用。
5. **等 A 分块的正确性依赖 `E_i` 只由 `A_k` 决定**：若未来加入机器相关的 release/eligibility（例如机器专属日历），块内排序会失效，必须退回带标签的 `H^m` 状态。
6. **`PROFILE-OPT` 用 LPT 上界剪枝**：上界差时状态多；上界低于真 OPT 时会漏解（实现上 `U` 来自可行调度，故不会低于 OPT，但若表调度实现有 bug 则危险）。
7. **定理 5 的适用范围窄**：只覆盖 m=2、统一容量、无资格限制；PART2 的根满足，DEC 的中间节点不满足。
8. **核的负结果可能被误读**：它只说明"贪心删除得到的核大"，不说明"不存在小核"；但结合 v0.9 的对偶支撑，证据方向一致。
9. **与 v0.9 的 `CHECK` 的接口**：`PROFILE` 叶要嵌入原证明 DAG，`RESOLVE` 的分支覆盖检查仍需 v0.9 的原实现；本轮只在容量层做了全量检查。
10. **时间测量是纯 Python 单次**：常数不可外推；状态数是更稳的指标。

---

## 12. 一句话最大风险

**画像表是伪多项式的：m=5、H=100 时已经要 1300 万状态/47 秒；若真实工时很大，"永远可检查"只是理论安慰，短证书仍然只在 LP 不可行时存在。**
