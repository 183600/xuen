## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（基线复现 → 这不是搬代码，是校准尺子）**
- **直觉**：大多数队伍把「复现基线」当杂务：跑通 `run_finetune_mmdit_frozen_vlm.sh`、接上 `run_server.py`、看到不报错就宣布复现完成。但官方基线是一个 6B 通才模型，真正的风险不在模型，而在**模型的「胶水」**：训练用 3 路图、评测给 4 路；训练是 EE 相对动作、评测要绝对 EE 目标；训练 horizon=30@30fps、示例 chunk=8；归一化必须用 checkpoint 自带的 `dataset_statistics.json`，若现场重算就会换一套 offset/scale；左/右 EE 统计量是合并的，按臂分开就破坏了官方先验。这些错任何一处，模型**照样能跑、动作也像模像样**，但已经悄悄偏离分布——我称之为**静默复现偏差（silent reproduction divergence）**。此时你去调数据、调增广、调双臂，所有增益都无法归因，因为你不知道「提升」是创新带来的，还是修 bug 修出来的。
- **严谨定义**：复现不是「运行成功」，而是**双跑等价（dual-run equivalence）**。定义 parity 张量 $\Pi=(\Pi_{struct},\Pi_{stat},\Pi_{teacher},\Pi_{closed},\Pi_{iface})$：
  - $\Pi_{struct}$：54/60/120 维、rotation-6D 前两列、mask 槽位、腿序；
  - $\Pi_{stat}$：normalize→denormalize 往返误差 $<\epsilon_1$，且重建统计量与官方 `dataset_statistics.json` 的 $o,c$ 逐维一致；
  - $\Pi_{teacher}$：同一 checkpoint、同一 obs，官方 `eval_local_episode` 路径与我们的 PolicyService 路径**逐维动作差 $<\epsilon_2$**；
  - $\Pi_{closed}$：`run_client` 全流程 0 拒绝、动作形状/范围合法；
  - $\Pi_{iface}$：相对→绝对 EE 位姿往返 $<\epsilon_3$、相机映射与 chunk 映射显式可审。
  只有 $\Pi$ 全绿，任何 I-claim 才允许进入 L0/L1/L2 记账。
- **反直觉点**：**复现本身就是最高性价比的得分动作**——官方 Base 已经是强基线，而「静默偏差」是负分黑洞。先把仪器校准到与官方逐维等价，等于免费拿到一个可复现的强起点，并让后续每一步增益第一次变得**可归因**。

**灵感 2（双臂协调 → 官方基线只有「统计对称」，没有「结构协同」）**
- **直觉**：官方把「双手协调」写进三大任务支柱（F20），但看训练/服务细节会发现：54 维动作把左右臂当成两条平行的 6 维相对位姿流；官方对双臂唯一的显式耦合是**左/右 EE 统计量等权合并**（F22），目的是让共享动作头有一个统一的双臂运动先验。这解决了「左右尺度不一致」，却**没有给模型任何显式的跨臂状态**：两臂之间的相对位姿、谁主谁从的角色、接触时刻的相位同步、避免互撞的排斥约束，都只能靠共享视觉 token 隐式猜。对「单臂主导」任务这没问题；但对「双主动协同」任务（一端持物、另一端操作；或双手同时折叠/叠放），这是结构性缺口。更关键的是：**我们至今不知道 32 个任务里哪些真的双主动**——靠任务名猜是不可靠的。
- **严谨定义**：先用数据把任务客观分层，再谈结构。定义**双臂耦合指数 BCI**：对任务 $\tau$、episode $e$，取双臂 EE 轨迹 $p_L(t),p_R(t)$ 与夹爪状态 $g_L(t),g_R(t)$，令速度 $v_a(t)=\lVert p_a(t)-p_a(t-1)\rVert$，定义
  - 活动能量 $E_a=\frac1T\sum_t v_a(t)^2$，活动比 $r=\min(E_L,E_R)/\max(E_L,E_R)$；
  - 运动耦合 $C=\max_{|k|\le K}\lvert\mathrm{corr}(v_L(t),v_R(t+k))\rvert$（$K=15$ 帧≈0.5 s）；
  - 接触同步 $S$：左右夹爪状态翻转事件在 $\pm5$ 帧内的配对比例（无翻转记 NaN）。
  任务级取中位数 $(R,C,S)$，按阈值分层为 **A 双主动协同 / B 主从-扶持 / C 单臂主导**（阈值待 L0 校准）。假设 $H_{bimanual}$：基线成功率在 A 类显著低于 C 类，即「双臂协调缺口」集中在 A 类。
- **反直觉点**：治疗双臂协调的第一步不是加模块，而是**给任务分层**；第二步也不是推翻基线，而是加一条**零初始化（identity）的协同残差通道**——初始化时它与基线逐维等价（parity 不破），训练后再长出错综的跨臂信号。**先不伤害基线，才谈得上增强基线。**

**两者统一**：基线复现校准「尺子」，双臂协调给尺子加上「第二个刻度」（分臂/协同指标）。没有复现，协同增益不可证；没有协同，复现最多只是打平。二者共同把上一轮的「数据引擎」从「盲目放量」改成「按可归因的计分轴放量」。

## 4. 设计原则（新增 PR6、PR7，其余保留）

- **PR6 复现先行（instrument calibration）**：任何创新点的增益，只有在 parity gate（§产物区 1.1）全绿后才被采信；复现阶段发现的偏差优先于所有模型改动。
- **PR7 协同杠杆（coordination lever）**：每个双臂创新必须声明它加的「协同原语」（共视/共帧/相位/角色/防撞）与它要移动的指标（碰撞率、相位滞后、双主动成功率），并证明初始化不破坏基线；拒绝「多喂数据自然就会协调」。
- PR1–PR5 保留。PR6 与 PR5 互补：PR5 管「数据教什么」，PR6 管「我们有没有资格测量它」。

## 6. 本轮最大风险

**一句话**：最大风险是「静默复现偏差」——训练用 3 相机/EE-相对/horizon 30/合并统计量，评测给 4 相机/绝对 EE 目标/任意 chunk，任一映射错位都会让基线「跑得通却已偏分布」，从而让本轮的双臂增益和上一轮的数据引擎增益同时失去归因；因此必须先用 parity gate 把尺子锁死，再谈协同。

# UniBot-V1 参赛创新点清单（新循环第 1 轮 · 清单 v1.2）

> 检索日期：2026-11-26（v1.0）、2026-11-27（v1.1）、2026-11-27（本轮 v1.2）；来源见 §7。承接 v1.1：I1–I9 只做增量修订，新增 I10（基线复现校准台）与 I11（双臂协同三件套）。**本轮的硬约束：I10 的 parity gate 未通过前，任何 I1–I9/I11 的增益不得进入真机预算排队。**

## 0. 本轮核心创新点（详细六要素）

### I10 基线复现校准台 ★★★★★（前置闸）

- **动机**：官方 Base 是 6B 通才模型，但训练/服务链里存在 6 类「能跑却偏分布」的静默偏差（P9/F22–F28）。复现的目标不是「跑通」，而是与官方 serving 路径**逐维等价**，从而让后续所有增益可归因。
- **与现有方案差异**：普通队伍用「不报错」当复现成功；本点用 parity 张量 + 双跑等价 + 显式接口桥，把复现变成可审计的测量仪器。
- **技术可行性**：高。官方已给出统一规范、预收集统计量、`eval_local_episode` 与 relative→abs 适配器（F22/F26），我们主要是「按规范对齐 + 写差分测试」，不重写数学。
- **所需资源**：1×24GB GPU（官方默认，F23）；1 人周工程；无需额外数据。
- **落地步骤**：①建立 6 类偏差清单与对应差分测试；②移植官方 `_compose_ee9 / active_rot6d_to_wbc50` 的语义到提交侧 PolicyService；③做官方 eval 路径 vs 我们路径的「双跑等价」；④用 `run_client` 过结构门禁；⑤输出复现报告卡（哪些维度已对齐、哪些是未核实假设）。
- **风险**：官方真实评测节拍/chunk 执行未公开（F28），本地只能证到「观察→动作」等价，证不到「闭环节拍」等价——需把节拍作为一等待核实项，并在提交侧做节拍自适应（按可用频率重采样/重规划）。

#### I10.1 六类静默偏差（Silent Divergence Classes）

| 类 | 偏差 | 官方事实 | 复现要求 |
|---|---|---|---|
| S1 | 相机数与映射 | 训练 3 路（head_left + 双腕），评测 4 路（左右 high + 双腕）；基线忽略 right_high（F24） | 显式表：`cam_left_high→head_left`、`cam_left_wrist→cam_wrist_left`、`cam_right_wrist→cam_wrist_right`；`cam_right_high` 基线不用；resize 对齐训练 `[336,448]` |

#### I10.2 parity 张量（严谨定义）

$$\Pi=(\Pi_{struct},\Pi_{stat},\Pi_{teacher},\Pi_{closed},\Pi_{iface})$$

- $\Pi_{struct}$：动作 54 维、状态 60 维、projector 120 维 = state‖mask；rotation-6D 前两列；29-DoF 腿序 `hip_pitch,hip_roll,hip_yaw,knee,ankle_pitch,ankle_roll`。
- $\Pi_{stat}$：对留出 episode 做 `normalize→denormalize`，要求 $\lVert\hat a-a\rVert_\infty<\epsilon_1$；重建的 $(o,c)$ 与官方 `dataset_statistics.json` 逐维比对。
- $\Pi_{teacher}$（**双跑等价**）：同一 checkpoint、同一 obs，官方 `eval_local_episode` 路径输出 $a^{off}$ 与我们的 PolicyService 输出 $a^{ours}$，要求 $\max|a^{ours}-a^{off}|<\epsilon_2$（初始 $\epsilon_2=10^{-4}$，先在同进程/同精度下比）。
- $\Pi_{closed}$：`run_client` 全流程 0 拒绝；动作形状、dtype、范围、夹爪方向合法。
- $\Pi_{iface}$：`T_abs` 组合往返 $<\epsilon_3$（初始 $10^{-6}$ m）；相机映射与 chunk 映射可审。

**门禁定义**：$G=\bigwedge \Pi$。$G=0$ 时，所有下游实验只允许记为「debug」，不得记为「创新增益」。

### I11 双臂协同三件套 ★★★★

- **动机**：官方把「双手协调」列为三大支柱（F20），但基线只有统计对称、没有结构协同（F22）；且 32 任务中哪些是「双主动」尚未被数据化分层（P10/Q10）。
- **与现有方案差异**：不靠「多喂双臂数据」碰运气；先用 BCI 分层锁定 A 类，再用**零初始化**跨臂适配器注入协同信号（初始化即基线，确保 parity），最后用推理期 guard 兜底。
- **技术可行性**：中-高。BCI 纯离线；适配器小（MLP/少量 cross-attn token）；guard 是后处理，复用 I3/I4 的 guard 栈。
- **所需资源**：BCI 全量轨迹统计 1 GPU 日；适配器训练 1×24GB（LoRA + 新参数）；DualArm DiverseManip（525 eps）下载约数 GB。
- **落地步骤**：①BCI 实测分层；②检验 $H_{bimanual}$（基线按类成功率）；③实现零初始化适配器并验证「初始化零扰动」；④A 类任务 L0/L1；⑤L2 真机 top 候选 + C 类回归。
- **风险**：协同信号梯度饥饿（零初始化 gate 一直不动）；工作空间锚定在某些任务失效；A 类增益不能迁移到真实双臂评测节拍。缓解见下。

#### I11.1 双臂耦合指数（BCI）与任务分层

```python
def bci(episodes, K=15, eps_E=1e-4):
    R, C, S = [], [], []
    for ep in episodes:
        pL, pR = ep.ee_pos["left"], ep.ee_pos["right"]      # (T,3)
        vL, vR = np.linalg.norm(np.diff(pL,axis=0),axis=1), np.linalg.norm(np.diff(pR,axis=0),axis=1)
        EL, ER = (vL**2).mean(), (vR**2).mean()
        r = min(EL,ER) / (max(EL,ER) + 1e-12)
        c = max(abs(np.corrcoef(vL[K:-K], np.roll(vR,-k)[K:-K])[0,1])
                for k in range(-K, K+1))
        s = gripper_transition_synchrony(ep.gl["left"], ep.gl["right"], tol=5)  # NaN if no transitions
        R.append(r); C.append(c); S.append(s)
    return dict(R=np.nanmedian(R), C=np.nanmedian(C), S=np.nanmedian(S))

# 分层（阈值待 L0 校准；先报告连续值，再报类别）
#  A 双主动协同：R >= 0.5 且 C >= 0.5
#  B 主从/扶持：0.1 <= R < 0.5 且 E_min > eps_E（一臂准静态持物）
#  C 单臂主导：R < 0.1 或 E_min <= eps_E
```

- **先验清单（仅假设，不是事实）**：FoldTowel、ArrangePlates、StackBowls、SyringeWaterTransfer 可能落在 A/B；HangCup、ZipUp、PlugCharger 可能落在 B/C。**以 BCI 实测为准，禁止用任务名直接下结论。**
- **缺口检验**：$\Delta_{bimanual}=\overline{SR}(C类)-\overline{SR}(A类)$，用同一基线 checkpoint 在本地可复现集上估计；若 $\Delta_{bimanual}$ 显著为正，A 类即本轮靶区。

#### I11.2 零初始化跨臂适配器（核心）

- **协同原语**：**跨臂相对位姿 + 工作空间锚定**。设 reset 时（每 episode 恰好一次，F18）记录双 EE 初始中点构造工作空间锚 $T_W$（base 朝向下、平移取双手中点）；每步构造特征
  $$\phi_t=\big[\mathrm{vec}(T_L^{-1}T_R),\ \mathrm{vec}(T_W^{-1}T_L),\ \mathrm{vec}(T_W^{-1}T_R)\big]$$
  （每段 xyz+rotvec 共 6 维，合计 18 维）。$T_W$ 锚定使特征对全局平移/旋转不变——这与「位置变化」泛化轴（P2）天然同向，是协同与泛化的双用途。
- **注入方式**：小 MLP $E_\phi$ 编码为协同 token $z$，以**零初始化输出层**接入 DiT 条件（cross-attn 额外 token，或对 projector 输出加零初始化残差门 $\alpha$）。初始化 $\alpha=0$ 时 $z$ 不改变任何 logits，**与我们刚校准的基线逐维等价**；训练时 $\alpha$ 从 0 长出，天然满足 PR6/PR7。
- **辅助损失**（只训练期用，不改推理接口）：
  - $\mathcal L_{rel}$：从共享 token 预测未来跨臂相对位姿 $\mathrm{vec}(T_L^{-1}T_R)_{t+k}$；
  - $\mathcal L_{phase}$：夹爪翻转事件的时间对比损失，鼓励双臂接触相位对齐（只在 A 类加权）；
  - $\mathcal L_{coll}$：运动段臂间距离的 hinge 惩罚 $\max(0,d_{min}-\lVert p_L-p_R\rVert)$。
- **训练**：VLM 冻结；DiT action head LoRA（官方现成 yaml，F23）+ 新适配器全参；先 32 任务全量，再按 BCI 对 A 类上采样。

```python
class ZeroInitCoordAdapter(nn.Module):
    def __init__(self, d=18, h=256, dim=1024):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(d,h), nn.SiLU(), nn.Linear(h,dim))
        nn.init.zeros_(self.net[-1].weight); nn.init.zeros_(self.net[-1].bias)  # identity at init
        self.alpha = nn.Parameter(torch.zeros(1))
    def forward(self, phi):                 # phi: (B,18)
        return self.alpha * self.net(phi)   # -> additive conditioning token; alpha=0 => baseline
```

#### I11.3 协同推理 guard（低成本兜底，复用 guard 栈）

```python
def coordination_guard(chunk, obs, task_class, cfg):
    # chunk: 左右 EE 绝对目标 xyz+rpy, (T,6) each
    if task_class != "A": return chunk
    for k in range(len(chunk)):
        pL, pR = chunk["left"][k,:3], chunk["right"][k,:3]
        d = np.linalg.norm(pL - pR)
        if d < cfg.d_min:                          # 防撞：沿连线最小分离
            chunk["left"][k,:3], chunk["right"][k,:3] = separate(pL, pR, cfg.d_min)
        # 相位：单侧夹爪闭合前，另一侧若处于扶持态则保持支撑（不提前撤离）
        if closing_soon(chunk,k,"left") and supporting(chunk,k,"right"):
            delay_release(chunk,k,"right",cfg.sync_frames)
    return chunk
```

- 该 guard 只在 A 类触发，C 类完全旁路 → 保证「不伤基线」可测。
- 与 PR2 单模型边界的关系与 I3/I4 相同：guard 是同一 PolicyService 内的后处理，需在合规清单中书面确认（沿用 v1.1 的确认项）。
