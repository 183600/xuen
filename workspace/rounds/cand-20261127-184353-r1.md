## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（机械臂 → 手臂不是执行器，是一台已标定好的移动量测臂）**

直觉：比赛给了 7-DoF 双臂、关节编码器、基座系 EE 位姿、4 路相机，却不给 depth。多数队伍把场景理解当纯视觉问题，去换更强的视觉编码器或更大的 VLM。反过来看：机械臂本身就是一根**带精确位姿读数的移动支架**，腕相机是 eye-in-hand 传感器，头立体对是一台固定基线的测距仪。于是三件原本很难的事都变便宜了：(a) **深度不用学**——头立体对已校正，三角测量即可得度量深度；(b) **外参不用猜**——数据集 `camera_params` 给了内参与立体外参，`state_d435`/`state_torso` 给了头相机相对躯干/基座的位姿，离线拟合一次即可；(c) **手眼不用手标**——32k 示教里腕相机随 EE 运动，静态场景点在多帧间提供约束，解 AX=XB 即可。核心反直觉点：**在给了标定元数据与本体感受的赛题里，「学深度」是把可算的量当成要学的量；机械臂的运动本身就是第二视角。**

严谨定义：设基座系 B、躯干系 T、末端系 E、头立体左/右相机系 C_L/C_R、腕相机系 C_W。本体感受给 T_B^E(t) ∈ SE(3)（由 xyz+rpy 构造，rpy 顺序须从官方代码确认）。头立体已校正，像素 (u,v) 的视差 d = u_L − u_R，深度

  Z = f_x · B / d，

反投影 p_{C_L} = Z · K_L⁻¹ [u,v,1]ᵀ，再经 T_B^{C_L} 变到基座系；T_B^{C_L} = T_B^T · T_T^{D435} · T_{D435}^{C_L}，离线由 `state_d435`/`state_torso` 拟合，评测期用 waist 关节正运动学 + 固定安装外参推出。腕部手眼 X = T_E^{C_W} 满足 AX = XB，其中 A = T_E(t)⁻¹T_E(t+1)，B = T_C(t)⁻¹T_C(t+1)（B 由静态场景特征跟踪 + 已知 EE 平移/头立体定位估计）。

**灵感 2（场景理解 → 动作需要的是「位姿 + 关系 + 不确定性」，不是语义标签）**

直觉：VLA 的典型失败不是「不认识杯子」，而是「知道是杯子，却不知道杯口在基座系哪里、离桌沿多远、会不会碰倒旁边的瓶子」。语义已由 VLM 提供，缺的是度量几何与关系。更关键的是，**场景图恰好是官方得分点的结构**：ArrangePlates 是盘子相对位置关系，StoreCups 是杯子进哪个格，ToolboxStorage 是工具与槽位对应，ColorArrangement 是颜色序，OrganizeBookshelf 是书的顺序。把场景图当作「VLM 语义」与「动作头」之间的共享中间语言，等于让策略显式优化得分点所定义的关系，而不是从像素里隐式猜。核心反直觉点：**场景理解的交付物不是一张分割图，而是一组可直接被动作消费的 SE(3) 目标与谓词；语义负责「是什么」，几何负责「在哪里、能不能动」。**

严谨定义：场景图 G = (O, R, Σ)，节点 o_i = (l_i, T_B^{o_i}, b_i, a_i, Σ_i)：语义标签、基座系位姿、包围盒/尺寸、可供性（抓取点、容器开口、铰链轴）、位姿协方差；边 r_ij = (pred, i, j, p)：谓词 pred ∈ {on, in, left_of, near, aligned, occludes} 及置信度。Σ_i 由视差噪声、平面残差、检测方差一阶传播。**下游消费者**：I3 的关键点 = 可供性 a_i 在图像上的投影；I9 的检索键 = (l_i, 尺度不变形状描述, 关系签名)，不再只靠外观；I5 的扰动重放 = 对 T_B^{o_i} 采样后重投影/重渲染；I1 的增广 = 按考纲卡采样位姿后做 3D 一致重渲染。

**两者统一：几何的三种角色（训练 / reset / 每步 guard）**

直觉：直接往推理链里塞一个场景理解大模型，会同时撞「单模型边界」和「66ms 预算」两道闸。正解是把几何拆成三种角色：(a) **训练期**——用立体深度/位姿生成辅助监督，蒸馏进单模型，推理时删掉辅助头，零额外开销（I12）；(b) **reset 期**——`reset()` 每 episode 恰好一次（F18），在此构建一次场景图，供 I9 检索、目标位姿与可行性检查（I10）；(c) **每步/chunk**——只保留轻量几何 guard（目标可见性、碰撞距离、位姿残差），不跑大模型（I6）。核心反直觉点：**场景理解要提分，未必要在每步都「看见」；把它放进训练信号与 episode 级预处理，既拿收益又不付推理税。**

严谨定义（PR6 三角色律）：任何几何信息只能以「训练监督 / reset 一次性 / 每步轻量 guard」三种角色之一进入系统；每步主推理保持单模型端到端。任一几何模块若无法归入这三种角色，默认不进计分通道。

## 2. 对第 2 轮痛点的增量修订

- P2（泛化缺口）：立体深度 + 度量位姿把「外观泛化」部分转成「几何泛化」——未见物品的尺寸/形状/落点可测，比纯外观嵌入更稳；但透明/反光是硬点（见 §6）。
- P4（无触觉）：接触段可用腕部运动视差 + EE 位姿估计「几何接触」（穿透量、离面距离），是 I3 之外的第二条无触觉缓解路径。
- P5（时间压力）：场景图 amortize 到 reset/chunk 边界，不占每步 66ms 预算。
- P8（示教质量）：重投影误差 / 位姿一致性可作为无监督质量分，补进 I2 的 per-episode 权重。
- 新增 **P9（标定与同步误差）**：数据集与评测 rig 的相机键名、内外参、base/torso 定义、30Hz vs 15Hz 时间同步若有偏差，会系统性污染几何，且比随机误差更难发现。这是本轮最大的新工程风险。

## 3. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

- **Q9（度量场景图的最小充分表示）**：在 480×640 头立体 + 腕部单目 + EE 位姿下，哪种表示（物体 SE(3)+尺寸、关键点+协方差、支撑平面+占据、关系图）能在 chunk 预算内给动作头足够信息？透明/反光/柔性物体（Syringe、杯、塑料袋）如何降级？
- **Q10（机械臂自标定与同步）**：从官方 `camera_params`/`state_d435` 恢复的外参在评测 rig 上是否一致？相机键名如何映射？base/torso 坐标与 30Hz 数据 vs 15Hz 部署的时间同步误差如何估计并补偿？
- **Q11（几何的角色分配）**：哪些几何必须进推理（reset 检索、chunk 目标位姿、guard），哪些只进训练（辅助深度/位姿监督、3D 增广）？边界用哪几个 L0 代理指标确定？

## 4. 设计原则（新增 PR6–PR7，其余保留）

- **PR6 三角色律**：几何信息只能以「训练监督 / reset 一次性 / 每步轻量 guard」三种角色出现；每步主推理保持单模型端到端。与 PR2（单模型边界）互补：PR2 管推理实体，PR6 管几何进入点。
- **PR7 度量优先律**：任何场景表示必须输出基座系 SE(3) + 协方差；只有语义 embedding、没有位姿与不确定性的「理解」不能进入动作决策。
- PR1–PR5 保留（第 1/2 轮）。

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2）

> 检索日期：2026-11-26（第 1 轮）、2026-11-27（第 2/3 轮）；来源见 §5。承接 v1.1：新增 I10–I12，深化 I1/I3/I5/I9，I2/I4/I6/I8 维持，I7 维持待裁撤。清单只增改不重置。本轮主轴：**把机械臂本体（立体头 + 腕相机 + EE/FK）当作已标定的度量传感器，用「训练蒸馏 / reset 场景图 / 每步轻量 guard」三角色接入，避免撞单模型边界与 66ms 预算。**

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I10 机械臂自标定度量场景图 ★★★★★（新，本轮核心）

- **动机**：动作失败的主因不是语义错，而是基座系下的度量位姿/关系缺失（P2/P4）；而官方已给头立体标定（F21）、D435/躯干/EE 位姿（F22）与 32k 示教，几何本可算出来。
- **与现有方案差异**：纯 VLA 队伍把 4 路 RGB 丢进视觉骨干隐式学几何；本点显式输出 G=(O,R,Σ)（基座系 SE(3)+尺寸+可供性+协方差），并把「支撑平面锚定」作为透明物体的降级通道。不是再加一个大模型，而是把已有标定/本体感受用起来。
- **技术可行性**：中-高。头立体已校正，SGBM/轻量 RAFT 即可；平面 RANSAC；开放词汇检测可复用 VLM 特征或 reset 期跑一次；融合为纯几何运算。单帧头立体在 0.6m 处深度误差约 3–4cm（F24），足够桌面粗定位，不足以接触段精定位——正好由 I3/I11 补。
- **所需资源**：离线标定脚本（无新数据）；推理期 SGBM 5–10ms（可下采样）或小 RAFT ~20ms GPU，amortize 到 reset/chunk 边界；检测在 reset/chunk 边界执行；场景图融合 <5ms。
- **落地步骤**：①核对相机键名映射与 `camera_params` 可用性；②离线拟合 T_B^{C_L}（用 `state_d435`/`state_torso`）与腕部手眼 X；③实现「立体深度 → 支撑平面 → 2D 检测 + 平面反投影 → 场景图」；④在 5 个多物体任务上做 L0 稳定性测试；⑤接入 I9 检索与 I3 关键点。
- **风险**：数据集与评测 rig 标定不一致/键名映射错误（缓解：L0 一致性验证；不一致则退化为 reset 期用支撑平面 + EE 相对几何自标定）；透明/反光导致立体失效（缓解：平面锚定 + 轮廓/遮挡边界，见 §1.4）；base/torso 坐标与时间同步（缓解：统一到 base、只用最新观测、不跨未知延迟插值）。

### I11 接近段主动感知 / 运动视差 ★★★（新，条件启用）

- **动机**：头立体远距精度不足（F24），腕部评测只给单目 color（F21/F23）；但机械臂在接近段本来就要运动，运动即基线。

### 1.1 头立体 → 支撑平面 → 场景图（I10）

```python
import numpy as np, cv2

# 离线常量：来自数据集 meta/info.json 的 camera_params + state_d435/state_torso 拟合
K_L, K_R, B = load_stereo_calib("camera_params.json")   # fx≈186, B≈0.05484m
T_B_CL = fit_head_extrinsic("state_d435", "state_torso") # 基座系 <- 左头相机

def stereo_metric_pointcloud(left, right, K_L, B, T_B_CL):
    disp = stereo_match(left, right)            # rectified；SGBM 或小 RAFT
    valid = disp > 1e-3
    Z = (K_L[0, 0] * B) / np.maximum(disp, 1e-3) # Z≈10.2/d (m)
    P_C = backproject(K_L, Z)                    # HxWx3
    return transform(T_B_CL, P_C), valid

def fit_support_plane(P_B, valid, thresh=0.01):
    pts = P_B[valid]
    n, h = ransac_plane(pts, thresh=thresh, iters=200)   # n·x + h = 0
    inlier_ratio = plane_inlier_ratio(pts, n, h, thresh)
    return (n, h), inlier_ratio

def plane_anchored_3d(box, K, T_B_C, plane):
    # 透明/反光降级：2D 框底边中点视线与支撑平面求交
    u, v = box.bottom_center
    r_C = np.linalg.inv(K) @ np.array([u, v, 1.0])
    r_B = T_B_C[:3, :3] @ r_C
    o_B = T_B_C[:3, 3]
    n, h = plane
    t = -(n @ o_B + h) / (n @ r_B)
    return o_B + t * r_B

def build_scene_graph(obs, lang):
    P_B, valid = stereo_metric_pointcloud(
        obs["observation.images.cam_left_high"],
        obs["observation.images.cam_right_high"], K_L, B, T_B_CL)
    plane, plane_conf = fit_support_plane(P_B, valid)
    dets = open_vocab_ground(obs["observation.images.cam_left_high"], lang)
    nodes = []
    for d in dets:
        p = plane_anchored_3d(d.box, K_L, T_B_CL, plane)       # 稳定落点
        ext = extent_from_depth(P_B, d.mask, valid)             # 透明时可能 None
        cov = propagate_cov(disp_var=1.0, plane_res=plane_conf, det_var=d.var)
        nodes.append(Node(label=d.label, p=p, extent=ext,
                          affordance=d.affordance, cov=cov))
    return SceneGraph(nodes, relations(nodes), plane, plane_conf)
```

### 1.3 reset 期场景图 + 结构化检索（I9 v2）

```python
def retrieval_key(node, graph, instruction):
    return concat([
        text_embed(instruction),                      # 语义
        shape_descriptor(node.extent),                # 尺度不变：长宽高比/开口尺寸
        relation_signature(node, graph),              # on/in/near/edge 谓词
    ])

class RetrievalAugmentedPolicy:
    def reset(self, first_obs=None):
        if first_obs is None:
            return
        self.graph = build_scene_graph(first_obs, self.lang)
        target = match_instruction_node(self.graph, self.lang)
        q = retrieval_key(target, self.graph, self.lang)
        hit = self.index.search(q, k=3)
        self.prior = hit.params if hit.dist < TAU else None   # 置信门控
        self._reset_done = True

    def get_action(self, obs):
        if not getattr(self, "_reset_done", False):
            self.reset(obs)
        chunk = self.vla.propose_chunk(obs, prior=self.prior)
        return self.geometric_guard(chunk, self.graph, obs)    # 轻量 guard
```

```python
def geometric_guard(chunk, graph, obs, d_safe=0.03):
    state = obs["observation.state"]
    out = []
    for a in chunk:
        p_ee = a.ee_pose if CONTROL_SPACE == "ee" else forward_kin(state, a)
        # 只做三类便宜检查，不跑大模型
        if min_distance(p_ee, graph.obstacles) < d_safe:
            break                                  # 截断，不执行危险段
        if not target_visible(graph.target, p_ee):
            break
        out.append(a)
    return out if out else fallback_safe_chunk(obs)
```

| 训练 | 1×24GB 起步（LoRA/frozen-VLM，F11）；8×A100 上限 | 维持 |
