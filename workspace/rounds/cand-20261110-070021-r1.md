# 第 42 轮（新循环第 2 轮） · 低秩证书 × 产学研：把证书从「单体工件」变成「可组合、可审计、可跨机构复用的低秩护照」（四层架构 v7）

> 承接第 41 轮 v18（CAHA 运行时自动机 × LCS 轻量分层证书 × CMC 看门狗）。第 41 轮把证书变成「运行时守卫」，但证书仍然是**单体、单机构、单域**的：谁签发、在哪有效、能不能被别人独立复核、组合后还成不成立，全都没有答案。本轮灵感词「LoRA」「产学研合作」正好提供两把互补的手术刀：**LoRA** 给出一个天然的「低维证书单位」——适配增量只活在一个 r 维子空间里，于是谱范数可精确廉价地算、可达集可用 r 个生成元紧致包住、证书本身也能被压缩成低秩对象；**产学研合作**给出一个天然的「多方证书市场」——学术界出基座与形式化验证器、产业界出领域适配器与真实数据、研究院出独立复核，证书必须像供应链上的护照一样可签发、可组合、可撤销、可跨域降级。二者合起来，把第 41 轮「证书即守卫」推进为「证书即护照」：守卫决定这一拍走不走，护照决定这张证书**由谁担保、在哪有用、还能信多久**。

## 0. 直觉与动机

**灵感 1（LoRA → 证书的低维化，而不是模型的小型化）**：第 41 轮最贵的两项是「谱范数/雅可比」与「全量重算」。LoRA 的增量 ΔW=BA 的秩 r≪min(d,k)，这带来三个此前没人利用的结构红利：
1. **精确而廉价的谱范数**：‖BA‖₂ 的非零奇异值等于 r×r 矩阵 Σ_B V_BᵀA 的奇异值，可在 O(dr²+r²k+r³) 内**精确**算出，不必再用 ‖B‖‖A‖ 这种松 1~10 倍的上界。这意味着适配器对 Lipschitz 常数的贡献可以做到「无松弛」，第 41 轮抱怨的证书紧致性在适配器项上直接消失。
2. **低秩可达集**：若输入在区间盒内，BAx=Σᵢ bᵢ(aᵢᵀx) 的像是一个只有 r 个生成元的 zonotope，而不是 d 维盒子；用 r 维生成元做区间传播，比全维 IBP 紧得多、比 CROWN 便宜得多。
3. **证书本身可以低秩**：护栏对参数的敏感度 ∇_θ m 也集中在低维子空间，可压成 (B_c, A_c, 残差) 三元组，使证书小到能当「护照」跨机构传输与秒级复核。
更激进的是反过来用：既然能算「哪些方向的适配是安全的」，就把微调本身限制在**可认证子空间**里（安全感知 LoRA）——只在该子空间内更新，秩预算是安全裕度预算，微调从「先训后证」变成「边证边训」。

**灵感 2（产学研 → 证书的联邦化，而不是把机构当背景板）**：现实里没有哪一方能独立给出端到端保证：学术界的基座没见过工厂的分布，产业界的适配器没有形式化证明，研究院的验证器拿不到全部数据。产学研合作的真正技术难点不是「合作」二字，而是**信任与责任的分解**：每方只承诺「在什么假设下、我保证什么、证据到哪一级、有效域多大」。这正好是一个 assume-guarantee 契约问题，而且与第 41 轮的 CAHA 守卫天然同构——只不过守卫的输入多了一项「护照信任」。于是：
- **护照格式**：证书变成 (主体哈希, 声明, 有效域, 有效期, 证据等级, 依赖, 签名)，可离线复核、可撤销、可绑定数据版本；
- **信任格**：证据等级 E0 自证 < E1 可复现基准 < E2 独立重放 < E3 形式化证明，组合取 meet，暴露「最弱一环」；
- **跨域降级**：护照携带有效域 D，离开 D 时用域 Lipschitz 把裕度按距离折减，并直接触发第 41 轮的单调保守转移（出域只能进 Degraded/SafeStop），使「产业域与学术域不同」从隐患变成可计算的护栏。
低秩与联邦在这里是**乘法关系**：正因为适配器低秩，它的证书才小到可以当护照流通；也正因为证书要跨机构流通，才必须把「秩、裕度、有效域、证据级」全部显式写进对象，而不是藏在附录的假设里。

**耦合**：LoRA 提供「可交换的低维证书单位」，产学研提供「证书交换的信任与责任规则」；CAHA 的守卫负责把「护照是否仍然可信」翻译成「这一拍走不走」。三者拼成一个闭环：任何一次跨机构复用，都同时消耗低秩证书的秩/裕度预算与护照的信任预算，任何一个预算耗尽都会在运行时以可用性下降或 SafeStop 的形式当场现形。

## 1. 形式化定义

**定义 32（低秩适配证书 RAC）**：设基座策略 π_θ，适配增量 Δθ=BA，rank(BA)≤r，安全裕度泛函 m(x;θ)。**秩 r 证书**是一个七元组
C_r=(r, β, α, Z_r, m₀, ρ_r, D; δ)，其中 β=‖B‖₂、α=‖A‖₂（**精确**谱范数，非上界），Z_r 为 r 生成元的低秩可达 zonotope 生成元组，m₀ 为基座裕度下界，D 为有效域，ρ_r 为适配器引入的认证裕度损失：
ρ_r(x)=L_out·‖BA x‖_{Z_r}+½L₂·‖BA x‖²_{Z_r}，‖·‖_{Z_r} 由 zonotope 支撑函数给出。
**可靠性**：对 x∈D，以置信 1−δ 有 m(x;θ+BA) ≥ m₀ − ρ_r(x)。当 r=d 时退化为全秩证书，故 RAC 是第 41 轮 IP-46 证书对象的严格精化。

**命题 32.1（适配器项无松弛）**：由于 β、α 取精确谱范数且 ‖BA‖₂ 可由 r×r SVD 精确得到，RAC 在「线性适配器对 Lipschitz 的贡献」这一项上没有任何谱范数松弛；剩余松弛只来自非线性输出头的 L_out 与二阶余项 L₂。

**定义 33（低秩证书代数）**：两个证书 C_{r₁}, C_{r₂} 的**合成**定义为 C_{r₁}⊕C_{r₂}=(r₁+r₂, max(β₁,β₂), max(α₁,α₂), Z_{r₁}⊕Z_{r₂}, min(m₀ᵢ), ρ_{r₁}+ρ_{r₂}+ρ_cross, D₁∩D₂)——合并两个 LoRA 后秩上界为 r₁+r₂，裕度损失次可加。定义**秩预算 R** 与**裕度预算 Δ**：admissible(C)=[r≤R ∧ ρ_r≤Δ]。于是存在偏序 C_r⪯C_{r'}（更紧、更省），以及「证书格」：meet=取更大秩/更大松弛/更小域（保守下界）。**命题 33.1（单调合成保声）**：⊕ 在 sound 证书上封闭，且 C⪯C' ⇒ 用 C' 替换 C 仍保声；因此适配器可以在线增删，只要重新做一次代数簿记而非全量重证。

**定义 34（证书护照 Passport）**：护照 P=(id, issuer, subject_hash, claim, D, [t₀,t₁], e, deps, sig)，subject_hash 绑定基座/适配器/数据版本，claim 为一条不变式或裕度阈值，e∈{E0,E1,E2,E3} 为证据等级，deps 为依赖护照集合。**复核谓词** Verify(P,ctx)∈{accept,warn,reject} 在无签发方参与下可判定，且对 subject_hash 或 claim 的任何篡改必然 reject。护照是证书的「可移植封装」：内部仍可携带 RAC 的低秩证据链。

**定义 35（信任格与 assume-guarantee 联邦）**：证据等级取格 E0⊑E1⊑E2⊑E3，meet=较弱者。若系统由护照集合 {P_i} 支撑、各自保证 G_i 且依赖假设 A_i，则联邦**契约可靠**当且仅当：(i) ⋀ᵢA_i 与各 G_i 的依赖闭包相容（无循环地互证）；(ii) 每条安全关键路径的信任 meet ≥ E2；(iii) 所有 claim 的有效域交集非空。**命题 35.1（最弱一环）**：组合护照的信任等级等于依赖 DAG 上证据等级的 meet；因此任何 E0 依赖都会把整条安全链降为 E0——这把「信任稀释」从模糊担忧变成可检查的图性质。

**定义 36（跨域护照与转移守卫）**：把有效域 D 表示为嵌入空间/语义图上的覆盖集（若干球的并）。定义到域距离 d(x,D)，域 Lipschitz 常数 L_D 满足 ‖∇m‖≤L_D。**跨域转移界**：x 在 D 外时 m(x)≥m_D−L_D·d(x,D)−ρ_r(x)。当 d(x,D)> (m_D−θ)/L_D 时护照失效，CAHA 守卫按单调保守性强制转入 Degraded/SafeStop。有效域、有效期、证据级共同构成护照的「信任三角」，任一项越界都只能使制度更保守、绝不能更激进。

## 2. 三大产出设计

### 2.1 IP-54 CERTIFIED-LORA（可认证低秩适配 CLoRA）
1. 精确谱范数与低秩 zonotope 传播：r×r SVD 求 ‖BA‖₂；用 r 个生成元做适配器输出的紧致区间界，替换掉全维 IBP。
2. 秩–裕度预算：把 (R,Δ) 作为微调约束，训练时对超出可认证子空间的方向做投影/惩罚；产出「边证边训」的适配器。
3. 合并代数：LoRA 合并、叠加、蒸馏都走定义 33 的 ⊕，自动更新秩上界与裕度损失，不重跑全量证书。
4. 有效秩监控：在线估计适配器有效秩（谱熵/能量集中度），一旦显著超过 r 立即吊销 RAC 并回退全秩证书。

### 2.2 IP-55 CERT-PASSPORT-FEDERATION（证书护照联邦 CPF）
1. 护照格式与签名/哈希绑定；支持离线复核、撤销列表、新鲜度（有效期+数据版本）。
2. 信任格与 assume-guarantee 组合检查器：把依赖建成 DAG，检查定义 35 的三条件，输出「最弱一环」报告。
3. 独立重放：研究院用第三方数据与验证器重跑 claim，把 E1 升到 E2；形式化内核通过的升到 E3。
4. 与 CAHA 联动：护照的信任等级与有效域直接编译成守卫谓词（接 IP-51/IP-53），信任下降等价于一次向更保守制度的安全转移。

### 2.3 IP-56 CERT-EXCHANGE（证书交换协议与产学研联合基准）
1. 统一的证书/护照交换格式（JSON + 可执行证据脚本），任何一方可离线 verify，不依赖中心服务。
2. 联合基准：学术界提交基座与形式化规约、产业界提交领域数据与适配器、研究院提交重放与红队，按「可复现证书数 / 单位验证成本」排名。
3. 认证成本分摊：把端到端保证分解到依赖 DAG 的叶子上，用 Shapley 值/最小成本覆盖给出「谁该为哪段验证付费」的参考分摊，缓解搭便车。
4. 红队与吊销演练：注入伪造/过期/超域护照，度量整条供应链的检测率与传播范围。

## 4. 实验设计（E79–E84 硬门槛）

| 实验 | 指标 | 门槛 |
|---|---|---|
| E79 低秩证书紧致度/成本 | ρ_r/ρ_full；证书算力比；谱范数误差 | ≤1.15x；≤0.1x；=0（精确） |
| E80 低秩代数保真 | r 枚适配器合成后预测裕度 vs 实测；合并后秩界 | 保声≥99.5%；裕度间隙≤5% |
| E81 护照往返与审计 | 跨栈复核接受率；篡改/过期/超域检测；复核延迟 | ≥99%；100%；<20ms |
| E82 跨域转移有效性 | 域外失效预测率；false-accept；false-trip | ≥95%；≤0.5%；≤5% |
| E83 联合基准复现 | ≥3 方贡献下的复现成功率；证书跨机构转移率 | ≥90%；≥95% |
| E84 端到端安全-可用 | 不安全事件；Nominal 占比；成功率；恢复时间；关键路径最低证据级 | 0；≥70%；≥85%；<2s；≥E2 |

回退：E79 不通过（低秩界仍松）→ 只保留精确谱范数 + 全秩证书；E81/E83 不通过（护照不可移植）→ 退回机构内护照 + 手工审计；E84 可用性不达标 → 放宽非关键路径证据级下限，但安全关键路径的 E2 底线不降。

## 5. 本轮最大风险

**一句话**：低秩 + 联邦的最大风险是**「低秩假设在部署中破裂，而基于它的护照仍在跨机构流通」**——一次局部适配器的有效秩上升或合并会把错误的低秩界沿证书供应链放大成系统性伪证，且比单体证书更隐蔽；因此 E80 的有效秩监控与 E81 的吊销演练必须作为安全关键路径的强制门，而不是可选项。

## 1. 符号体系（承接定义 32–36）

| 符号 | 含义 | 定义 |

| C_r | 秩 r 适配证书 RAC | (r, β, α, Z_r, m₀, ρ_r, D; δ)，m(x;θ+BA)≥m₀−ρ_r |
| β, α | 适配器精确谱范数 | β=‖B‖₂, α=‖A‖₂；非上界 |
| Z_r | 低秩可达 zonotope | BAx=Σᵢbᵢ(aᵢᵀx)，r 个生成元的紧致区间 |
| ρ_r | 适配器认证裕度损失 | L_out‖BAx‖_Z + ½L₂‖BAx‖²_Z |
| ⊕ | 低秩证书合成 | (r₁+r₂, 裕度次可加, 域交, 信任 meet) |
| (R,Δ) | 秩预算 / 裕度预算 | admissible ⟺ r≤R ∧ ρ_r≤Δ |
| P | 证书护照 | (id, issuer, subject_hash, claim, D, [t₀,t₁], e, deps, sig) |
| e | 证据等级 | E0 自证 ⊑ E1 复现 ⊑ E2 独立重放 ⊑ E3 形式化 |
| ⊓ | 信任 meet | 组合护照信任=依赖 DAG 证据级的 meet（最弱一环） |
| d(x,D), L_D | 域距离 / 域 Lipschitz | 出域时 m(x)≥m_D−L_D·d(x,D)−ρ_r |

## 2. 关键算法（伪代码）

### IP-54 CLoRA：精确谱范数与低秩区间传播
```
def rank_cert(B, A, base_cert, domain):
    # 精确谱范数：BA 的非零奇异值 = Σ_B V_B^T A 的奇异值
    Ub, Sb, Vb = svd(B, full_matrices=False)        # O(d r^2)
    M = diag(Sb) @ Vb.T @ A                          # r×k, O(r^2 k)
    beta, alpha = Sb[0], svd(A, compute_uv=False)[0]
    norm_BA = svd(M, compute_uv=False)[0]            # 精确, O(r^2 k)
    # 低秩可达集：input box [xl,xu] -> r 个生成元
    xc = (xl + xu) / 2; rad = (xu - xl) / 2
    gens = [abs(A[i] @ rad) for i in range(r)]       # 标量半宽
    Z = LowRankZonotope(B, gens)                     # r 个生成元
    rho = lambda x: L_out * Z.support(x) + 0.5*L2*Z.support(x)**2
    return RAC(r=B.shape[1], beta=beta, alpha=alpha, Z_r=Z,
               m0=base_cert.m0, rho_r=rho, D=domain, delta=base_cert.delta)
```

### IP-54 秩/裕度预算下的安全感知微调
```
def certified_lora_step(W, grad, R, Delta, cert):
    U, S, Vt = svd(grad, full_matrices=False)
    r_eff = effective_rank(S)                        # 谱熵/能量集中度
    if r_eff > R: grad = project_to_top_r(grad, R)   # 只动可认证子空间
    W_new = W - lr * grad
    if cert_after(W_new, cert).rho_r > Delta:        # 裕度预算耗尽
        W_new = backtrack(W, W_new)                  # 回退到可认证步长
    return W_new, recertify(W_new, cert)
```

### IP-55 CPF：护照组合与信任检查
```
def compose_passports(passports, claim, domain):
    deps = build_dependency_dag(passports)
    if has_cycle(deps):                      return reject("循环互证")
    e = meet_all(p.e for p in passports)     # 最弱一环
    D = intersect_all(p.D for p in passports)
    if D is empty:                           return reject("有效域为空")
    for p in passports:                      # 有效期/新鲜度/撤销
        if not fresh(p) or revoked(p):       return reject("过期/已撤销")
    if is_safety_critical(claim) and e < E2: return reject("证据级不足")
    return Passport.compose(claim, D, e, deps, sign=True)
```

### IP-54 ⊕ IP-51：低秩合并 / 域外转移触发
```
def on_adapter_merge(c1, c2, automaton):
    c = c1 ⊕ c2                              # r=r1+r2, rho 次可加
    if c.r > R or c.rho_r > Delta:
        automaton.force(Degraded)            # 裕度/秩预算耗尽 -> 保守
    if not subset(domain_now, c.D):
        automaton.force(SafeStop)            # 超域 -> 强制保守
    return c
```

### IP-56 CERT-EXCHANGE：离线复核
```
def verify_offline(passport, evidence_bundle, context):
    if hash(passport.subject) != evidence_bundle.subject_hash: return REJECT
    if not verify_signature(passport, passport.issuer):        return REJECT
    if not in_validity(passport, context.t):                    return REJECT
    if not in_domain(context.x, passport.D):                    return REJECT
    ok = replay(evidence_bundle.script, passport.claim)         # 可执行证据
    return ACCEPT if ok else WARN                               # 不确定即 WARN
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 正确性保证 |
|---|---|---|
| IP-54 精确谱范数 | O(dr²+r²k+r³) | 适配器 Lipschitz 项**无谱松弛**；r=d 退化为全秩 |
| IP-54 低秩区间传播 | O(r·|x|) vs 全维 O(d·|x|) | zonotope 包含真实可达集，r 维支撑函数给保守界 |
| IP-54 合并代数 | O((r₁+r₂)²·…) | ⊕ 在 sound 证书上封闭；裕度次可加保声 |
| IP-55 护照组合 | O(|P|+|deps|)（DAG 拓扑） | 三条件检查通过 ⟹ 契约可靠；篡改必 reject |
| IP-55 信任 meet | O(|deps|) | 组合信任=最弱依赖，泄露「信任稀释」 |
| IP-56 离线复核 | O(证据脚本) + O(1) 哈希/签名 | 无中心服务可判；不确定降为 WARN |
| IP-51 域外守卫 | O(1) 距离查询（覆盖集索引） | 出域只能更保守；d(x,D)>(m_D−θ)/L_D ⟹ 护照失效 |
| IP-52 证书压缩 | O(r_c·d) 存储 | 低秩证书只放宽存储项，sound 不变 |

## 4. 实验设计（E79–E84，硬门槛）

| 实验 | 指标 | 门槛 |
|---|---|---|
| E79 低秩证书紧致度/成本 | ρ_r/ρ_full；证书算力比；谱范数误差 | ≤1.15x；≤0.1x；=0（精确） |
| E80 低秩代数保真 | r 枚适配器合成后预测裕度 vs 实测；合并后秩界 | 保声≥99.5%；裕度间隙≤5% |
| E81 护照往返与审计 | 跨栈复核接受率；篡改/过期/超域检测；复核延迟 | ≥99%；100%；<20ms |
| E82 跨域转移有效性 | 域外失效预测率；false-accept；false-trip | ≥95%；≤0.5%；≤5% |
| E83 联合基准复现 | ≥3 方贡献下的复现成功率；证书跨机构转移率 | ≥90%；≥95% |
| E84 端到端安全-可用 | 不安全事件；Nominal 占比；成功率；恢复时间；关键路径最低证据级 | 0；≥70%；≥85%；<2s；≥E2 |

回退路径：E79 不通过 → 保留精确谱范数 + 全秩证书；E81/E83 不通过 → 机构内护照 + 人工审计；E84 可用性不达标 → 放宽非关键路径证据级下限，安全关键路径 E2 底线不降。

## 5. 风险与缓解

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 低秩假设破裂（有效秩上升、多次合并/继续训练） | 高 | 有效秩在线监控；合并即重算 ⊕ 簿记；超秩立即吊销 RAC 回退全秩 |
| 信任稀释：E0 依赖把整链降级 | 高 | 信任 meet 显式可视化；安全关键路径 E2 硬底线；独立重放升级 |
| 伪造/过期/超域护照跨机构传播 | 高 | 哈希绑定主体+数据版本；签名+撤销列表；红队吊销演练；离线 verify 三重检查 |
| 域外推失败（产业域≫学术域） | 中 | 域描述子+域距离守卫；出域单调保守；分域重证而非硬套 |
| 认证成本分摊博弈不稳定（搭便车） | 中 | Shapley/最小覆盖作参考分摊；联合基准公开验证成本 |
| 证书压缩丢证据链 | 低-中 | 低秩证书附可执行证据脚本；压缩只作用于存储，复核仍可重放 |
| 护照格式碎片化 | 中 | IP-56 统一交换格式 + 可执行证据；版本兼容与弃用策略 |

## 6. 本轮最大风险

**一句话**：低秩 + 联邦的最大风险是**「低秩假设在部署中破裂，而基于它的护照仍在跨机构流通」**——一次局部适配器的有效秩上升或合并会把错误的低秩界沿证书供应链放大成系统性伪证，且比单体证书更隐蔽；因此 E80 的有效秩监控与 E81 的吊销演练必须作为安全关键路径的强制门，而不是可选项。
