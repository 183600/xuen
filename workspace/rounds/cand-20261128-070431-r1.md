### 第 6 轮灵感驱动研究记录（新一轮循环第 1 轮，承接 CADVS-v5）

**灵感词**：步骤分、通用操作

**继承关系**：第 5 轮 CADVS-v5（IP-493~496）把 v4 的「规则提议 + 七硬门」升级为「认证的生成式执行」（CGE）：流匹配提议 π_θ^FM、嵌入记忆固化 LMEM-v2、情感调制 FAMK、EFA-v5 级联选证，并证明定理 5（调制单调）、6（证书不变性/提议无关）、7（固化有界）、8（七锚完备保持），执行集 Exec_CADVS-v5 ⊆ Exec_CADVS-v4 ⊆ … ⊆ Exec_v29。本轮不推翻 v5，而是补 v5 的三个结构性短板：(a) 证书是**整条轨迹的全有全无**判定，长程通用操作里「做了 80% 但没完成」与「完全没做」在监督信号上等价，固化只能吃到稀疏的全成功样本，正是 v5-R57 自指回路难破的根源；(b) v5 的流提议对**跨任务/跨物体的通用操作**只有条件化泛化，缺少可复用、可组合、带接口契约的**技能算子**，组合处只能整段重验，组合爆炸且接口错配无人负责；(c) 「进度」与「安全」被压在同一个二值门里，既无法表达部分进展，也无法把「安全但未完成」与「不安全」区分开。两个灵感词统一为主题「认证的步骤信用与通用操作组合」（Certified Step Credit & General Operator Composition），形成 CADVS-v6（IP-501~504）。本轮自律：**硬门数量仍不增**（维持七门），且**步骤分绝不替代门**——门是二值安全真值，步骤分是正交的进度真值；执行集嵌套升级为 Exec_CADVS-v6 ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29。

**直觉与动机**：

1. **步骤分 → 把「安全真值」与「进度真值」拆成两根正交轴**。直觉：门回答「这段执行安不安全」（二值、fail-closed、不可协商）；步骤分回答「这段执行推进了多少」（连续、可加、用于学习与排序）。二者不能合并——一旦把部分进度写进门的通过条件，安全边界就被「看起来完成」腐蚀。因此设计 CSCK（认证步骤信用核）：把长程任务分解为带检查点的子目标链 Φ=(φ_0,…,φ_K)，每段信用 c_k = pass_k · prog_k，其中 pass_k 是该段七门合取（任一失败则 c_k=0，**不安全段零信用**），prog_k 是**外部验证器**测得的保守进度增量（独立感知 + 审计过的进度函数 ρ，不由提议策略自报）。总信用取**前缀截断**：C(ξ)=Σ_{k≤k*} w_k c_k / Σ_k w_k，k* 为第一个失败检查点——这样「局部合规」不会被加总成「全局已认证」。定理 9（步骤分可靠性）：C>0 ⟹ 前缀各段全过门且达检查点；C=1 ⟹ 任务完成且全程安全。关键：步骤分只用于**排序/学习/解释**，从不扩大执行集。

2. **通用操作 → 从「整段轨迹」升级为「带契约的技能算子组合」**。直觉：通用操作不是一条更长的轨迹，而是**可复用的算子库**：reach/grasp/transport/place/insert/tool-use…，每个算子有自己的前/后置条件、证书模式与信用函数。组合的正确性不靠「再整段验一遍」，而靠**类型化接口契约**：Post_{o_j} ⟹ Pre_{o_{j+1}}（或经带证书的适配器 A_j 桥接）。定理 10（组合可靠性）：若各算子在其段上已认证且接口契约成链，则组合计划可执行且其证书成立；组合信用取**瓶颈 min_j c_{o_j}**（安全认证）与**前缀加权和**（进度信号）两种代数，前者保守、后者密集。这把 v5 的「任意生成器」进一步结构化为「任意生成器 + 可组合技能语法」，让跨任务泛化从「条件化记忆」升级为「算子复用 + 契约适配」。

3. **步骤分 × 通用操作 → 直接攻 v5-R57 的自指固化**。直觉：v5 只能拿「全成功 ∧ 人工抽检」的片段固化，样本极稀疏，策略只能在自己铸证的少数片段上自我强化。有了认证步骤信用，固化可以吃「**已过门且外部验证有真实进度**」的部分片段，信号密度提升一个量级；更关键的是，信用的**锚在外部**（独立感知的子目标谓词 + 冻结的进度验证器 + 结局验证），不再由策略自己的证书单独背书，从结构上削弱自指。诚实边界：外部验证器与子目标谓词本身成为新的信任根，可被感知对抗/OOD/规格错误污染——这是本轮最大风险。

**关键洞见**：v5 回答「任意生成器如何不改变证书边界」；v6 回答「当任务是长程、通用、可分解时，如何在不新增门、不放宽安全的前提下，获得密集且可组合的进度信号」。核心操作是把认证拆成**两条正交轴**：安全轴（七门，二值，fail-closed，不可学习）与进度轴（认证步骤信用，连续，外部锚定，可学习）。执行集 Exec_CADVS-v6 ⊆ Exec_CADVS-v5 由「同门 + 契约成链 + 前缀截断」三重保证；ECS_v6 = ECS_v5 · η_credit · η_compose，两个软因子 ∈[0,1] 只降不升。

**形式化目标（增量）**：
1. 子目标链：Φ=(φ_0=true, φ_1,…,φ_K)，检查点 0=τ_0<τ_1<…<τ_K；段 ξ_k=x[τ_{k-1}:τ_k]。
2. 段信用：c_k = pass_k · prog_k，pass_k=∧_i kc_i(ξ_k;τ_i^5)，prog_k=clip(ρ(x_{τ_k})−ρ(x_{τ_{k-1}}),0,1)，ρ 为外部验证进度势。
3. 前缀信用：C(ξ)=Σ_{k≤k*} w_k c_k / Σ_{k≤K} w_k，k*=min{k: pass_k=0 ∨ φ_k(x_{τ_k})=false}；C=1 ⟺ 全段过门且 φ_K 达成。
4. 通用算子：o=(Pre_o,Post_o,Args_o,π_o^FM,Cert_o,c_o)；计划 P=o_1⋯o_n 满足 Post_{o_j}⟹Pre_{o_{j+1}}（或经认证适配器 A_j 桥接）。
5. 组合代数：C_safe(P)=min_j c_{o_j}；C_prog(P)=前缀加权和；恒有 C_safe ≤ C_prog。
6. 定理 9（步骤分可靠性）、定理 10（算子组合可靠性）、定理 11（信用-安全正交/嵌套保持）、定理 12（外部锚定固化的反博弈上界，经验性）。
7. Exec_CADVS-v6 = {x∈Exec_v5 : contract_chain(x) ∧ prefix_certified(x)} ⊆ Exec_v5。

**本轮最大风险**：**外部进度锚成为七门之外的新信任根**——步骤分把「部分成功」变成一等优化目标，而子目标谓词与外部进度验证器不被七门覆盖；感知对抗、OOD 场景或任务规格错误一旦污染 ρ/φ，密集信用就会成为比 v5 稀疏全成功更强的证书博弈通道，把「局部合规 + 错误进度」加总成虚假完成，而七门对此完全无感。

## 2. 关键算法骨架

### IP-501 CSCK：认证步骤信用核（检查点处触发，非 1 kHz 环）

```python
@dataclass
class CertifiedStepCreditKernel:
    """CSCK：把长程任务拆成带检查点的子目标链，给每段打认证信用。
    红线：信用只做排序/学习/解释，绝不替代七门，绝不扩大执行集（定理 9/11）"""
    phi: list            # φ_k 外部子目标谓词，冻结只读
    rho: Any             # 外部进度势（独立感知 + 审计模型），冻结只读
    weights: np.ndarray  # w_k > 0, 和为 1

    def score(self, plan, segments) -> CreditReport:
        pass_bits = [all_gates(seg, tau_v5) for seg in segments]   # 七门合取
        prog = [clip(self.rho(x_at(tau_k)) - self.rho(x_at(tau_prev)), 0.0, 1.0)
                for tau_prev, tau_k in zip(plan.taus[:-1], plan.taus[1:])]
        c = [p * g for p, g in zip(pass_bits, prog)]                # 不安全段零信用
        k_star = next((k for k in range(len(segments))
                       if not pass_bits[k] or not self.phi[k+1](x_at(plan.taus[k+1]))),
                      len(segments))
        C = float(np.sum(self.weights[:k_star] * c[:k_star]))       # 前缀截断
        return CreditReport(pass_bits, prog, c, k_star, C,
                            truncated=(k_star < len(segments)))

    def certificate(self, rep: CreditReport) -> str:
        # C=1 才签"完成"；0<C<1 只签"前缀安全的部分进度"，永不签完成
        return "TASK_COMPLETE" if rep.C >= 1.0 - 1e-9 else "PARTIAL_CERTIFIED"
```

### IP-502 GOLC：通用算子库与组合核（准入时域，离线建库）

```python
@dataclass
class Operator:
    oid: str
    pre: Callable          # Pre_o：世界状态谓词（类型化：物体位姿/抓取态/空间关系）
    post: Callable         # Post_o
    proposal: Any          # π_o^FM：条件流匹配提议（共享底座 + 算子 head）
    cert_schema: Any       # Cert_o：该算子适用的七门子集与阈值模式
    credit: Callable       # c_o(seg) = pass·prog，复用 CSCK 的段逻辑

@dataclass
class GeneralOperatorCompositionKernel:
    """GOLC：把通用操作写成带接口契约的算子链。
    组合正确性靠类型化契约，不靠整段重验（定理 10）"""
    lib: dict              # oid -> Operator
    adapters: dict         # (oid_j, oid_{j+1}) -> 已认证适配器 A_j

    def compose(self, plan_ids, world) -> CompositePlan:
        ops = [self.lib[oid] for oid in plan_ids]
        margins, ok = [], True
        for a, b in zip(ops[:-1], ops[1:]):
            m = interface_margin(a.post, b.pre, world)     # Post⟹Pre 的软边际
            if m < 0:                                      # 类型/语义错配
                ad = self.adapters.get((a.oid, b.oid))
                if ad is None or not ad.certified:
                    ok = False                             # fail-closed：契约不成链
                    margins.append(m)
                    continue
                m = ad.margin(world)
            margins.append(m)
        return CompositePlan(ops, margins, contract_ok=ok)

    def composite_credit(self, plan: CompositePlan, reps) -> tuple[float, float]:
        c_safe = min((r.C for r in reps), default=0.0)      # 瓶颈：最弱环
        c_prog = prefix_weighted_sum(reps)                  # 密集进度信号
        return c_safe, c_prog
```

### IP-504 EFA-v6：七门不变 + 契约链 + 步骤信用排序

```python
@dataclass
class EvidenceForgingAssemblerV6:
    """EFA-v6：先由 v5 选证（七门不变），再做契约检查与信用打分。
    信用不参与准入，只影响排序与上报（定理 11）"""
    v5: EvidenceForgingAssemblerV5
    csc: CertifiedStepCreditKernel
    gol: GeneralOperatorCompositionKernel

    def select(self, x0_state, t_now, rule_id, context):
        ok, plan, why = self.v5.select(x0_state, t_now, rule_id, context)
        if not ok:
            return False, None, why                        # v5 的 fail-closed 原样保留
        comp = self.gol.compose(plan.operator_ids, context.world)
        if not comp.contract_ok:
            return False, None, 'CONTRACT_MISMATCH'        # 契约不成链即拒绝，不放松门
        rep = self.csc.score(plan, plan.segments)          # 只做信用，不改准入
        return True, plan, ('FORGED_CSC' if rep.C >= 1.0 else 'PARTIAL_CERTIFIED')

    def ecs_v6(self, base_v5: float, rep, comp) -> float:
        eta_credit = rep.C                                 # ∈[0,1]
        eta_compose = float(np.prod([sigmoid(KAPPA * m) for m in comp.margins]))
        return base_v5 * eta_credit * eta_compose           # 只降不升
```

| GOLC.compose | O(n·(类型检查 + m_j)) | O(n) | n≤8 | < 1 ms（谓词/缓存） |
| GOLC.composite_credit | O(n) | O(1) | — | < 0.05 ms |
| CACK 固化 | O(n_seg·E·d_model) DP-SGD | O(θ) | n_seg~50k 段 | 离线，分钟~小时 |
| 反事实信用估计 | O(n_seg·n_cf) | O(n_seg) | n_cf=4 | 离线 |
| EFA-v6 增量 | O(1)（先复用 v5） | O(1) | — | < 0.05 ms |
| 在线控制环 | 与 v5 相同 | — | — | **P99 仍 ~0.55 ms（无回归）** |

**通信开销**：算子库/适配器证书为签名制品（~百 KB 级，低频下发）；段信用与算子标签随记忆原型上报（DP，~2 KB/站）；φ/ρ/V_ext 只在本地或审计侧运行，原始感知数据不出端。

**为何不加重控制环**：v6 的所有新增量都在「准入/离线」时域——契约检查是谓词级、信用打分在检查点触发、固化离线。1 kHz 环仍只消费 v5 的缓存证书与预计算阈值。

## 4. 正确性论证（增量更新）

### 引理 45（子目标细化下的信用单调性）

**陈述**：设 Φ' 由 Φ 在某段内插入额外检查点得到，权重按段长重归一（总权重守恒），且 ρ 为保守进度势（细化不虚增进度）。则对任意计划 ξ，C_{Φ'}(ξ) ≤ C_Φ(ξ)。

**证明**：细化只可能让首个失败检查点 k* 提前或不变（新增检查点只能新增失败条件）；每段的 prog 之和在保守 ρ 下不超过原段 prog；前缀截断 + 权重守恒 ⇒ 总信用不增。∎

### 引理 46（接口契约边际与 Lipschitz 传播）

**陈述**：若接口边际 m_j = margin(Post_{o_j}, Pre_{o_{j+1}}) ≥ 0，且各谓词相对世界状态 Lipschitz 常数为 L_j，则组合链上的契约违反量 ≤ Σ_j L_j·ε_j，其中 ε_j 为第 j 段执行误差。当 m_j ≥ L_j·ε_j 时，实际执行仍满足下一算子前置条件。

**证明**：由谓词 Lipschitz 性与三角不等式逐段归纳。∎

**工程含义**：接口契约不是布尔黑箱——它带可度量的安全边际，可与 v5 的管/误差界对接（若继承 v6 的鲁棒门则更紧）。

### 引理 47（外部进度锚的误差传播，诚实界）

**陈述**：设外部进度势误差 |ρ̂−ρ| ≤ ε_ρ、子目标谓词误判率 ≤ ε_φ、验证器漏检率 ≤ ε_v。则步骤信用相对真值的偏差 |Ĉ−C| ≤ Σ_k w_k(ε_ρ + ε_φ) 以相应概率成立，且误判「完成」的概率 ≤ ε_φ + ε_v。**该界无结构下界**：ε_ρ、ε_φ、ε_v 由感知分布外行为决定，不能被七门约束。

**证明**：逐项误差有界 + 权重归一 + 并集界。∎

### 定理 9（步骤分可靠性）

**陈述**：对任意计划 ξ 与信用 C(ξ)：(i) C(ξ)>0 ⟹ ∀k≤k*，pass_k=1 且 φ_k(x_{τ_k})=true；(ii) C(ξ)=1 ⟹ k*=K、全段过七门、φ_K 达成（任务完成）且 V_ext 确认；(iii) C 是真实进度的保守下界（在 ρ 保守时）。

**证明**：c_k=pass_k·prog_k 且 pass_k∈{0,1}；pass_k=0 ⇒ c_k=0；前缀截断停在首个失败处；权重为正、prog_k≤1。故信用非零必须以安全与检查点为前提，满信用必须以任务完成为前提。∎

### 定理 10（通用算子组合可靠性）

**陈述**：若 (C1) 每算子 o_j 在其段 ξ_j 上已认证（pass=1）；(C2) 相邻接口 Post_{o_j}⟹Pre_{o_{j+1}} 成立或由已认证适配器 A_j 桥接；(C3) 适配器证书成立；则组合计划 P=o_1⋯o_n 可执行且安全，且 C_safe(P)=min_j c_{o_j} ≤ 每个 c_{o_j}。

**证明**：对 j 归纳。C2 保证 o_{j+1} 的前置条件在 o_j 后成立；C1/C3 保证各段安全门成立；组合轨迹的安全门合取 = 各段 pass 的合取；min 为下界。∎

### 定理 11（信用-安全正交与嵌套保持）

**陈述**：步骤信用与算子组合只向准入**追加合取约束**，不修改任何 kc_i 或 τ^5；因此 Exec_CADVS-v6 ⊆ Exec_CADVS-v5 ⊆ … ⊆ Exec_v29。且对任意计划，安全真值 {kc_i} 与信用值 C 相互独立：改变 C 不能翻转任何 kc_i。

**证明**：Exec_v6 定义为 Exec_v5 ∩ {contract_chain ∧ prefix_certified}；kc_i 与 τ^5 原样继承；信用是已过门段上的函数，不进入门的谓词。∎

### 定理 12（外部锚定固化的反博弈上界——经验性）

**陈述**：在 (D1) φ、ρ、V_ext 冻结且不被固化梯度触碰；(D2) 训练段要求 pass=1 ∧ V_ext 确认 prog>0 ∧ 随机人工抽检；(D3) KL(π_new‖π_old)≤ε_KL 且 DP-SGD 下，则 (i) 策略漂移 ≤ Pinsker 总变差界；(ii) 执行集只缩不涨；(iii) 信用博弈率 ≤ V_ext ∪ 人工抽检在留出红队集上的经验检测率。**无先验根除保证**（诚实边界）。

**证明**：(i) KL–TV/Pinsker；(ii) 谓词不变（定理 11）；(iii) 按经验检测率定义，且引理 47 表明 V_ext 可被 OOD 绕过，故只能给经验上界。∎

### 定理 v6（双轴认证总装）

**陈述**：在 v5 假设 (B1)~(B7) 及新增 (B8) φ/ρ/V_ext 冻结且审计 下：
(i) Exec_CADVS-v6 ⊆ Exec_CADVS-v5（同门 + 契约链 + 前缀截断）；
(ii) 步骤信用不扩大执行集、不替代门（定理 9/11）；
(iii) 组合证书由契约链归纳成立（定理 10）；
(iv) 信用细化单调（引理 45）；
(v) 外部锚定固化有界，且博弈率仅经验上界（定理 12，诚实边界）；
(vi) 七锚完备性保持（v5 定理 8），CSCK/GOLC/CACK 均为提议/记忆/进度层，不新增安全锚。

**证明**：(i)(ii) 定理 11；(iii) 定理 10；(iv) 引理 45；(v) 定理 12；(vi) 锚集合不变。∎

**诚实声明**：(B8) 是新的、**七门覆盖不到的信任根**——φ 的任务规格可能错、ρ 的感知可能被对抗/OOD 污染、V_ext 可能系统性漏检；引理 47 只给误差传播，不给下界。信用信号的密度正是它的风险：越密集、越可学，越值得博弈。

## 5. 实验设计与初步结果（仿真，单机；实机/舰队列入第 7 轮）

### 5.1 实验设计

- **平台**：MuJoCo 3.x + MJX；长程通用操作基准（LIBERO/CALVIN 风格 + 自建 UniBot-Long 20 任务，每任务 3–8 个子目标）；算子库 12 个（reach/grasp/transport/place/insert/open/pour/tool-use…）；外部进度势用独立腕部相机 + 冻结感知模型。

## 7. 本轮最大风险（最终确认）

**一句话**：**外部进度锚成为七门之外的新信任根**——步骤分把「部分成功」变成一等优化目标，而子目标谓词与外部进度验证器不被七门覆盖；感知对抗、OOD 场景或任务规格错误一旦污染 ρ/φ，密集信用就会成为比 v5 稀疏全成功更强的证书博弈通道，把「局部合规 + 错误进度」加总成虚假完成，而七门对此完全无感。
