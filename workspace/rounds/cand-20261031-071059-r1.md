# 第 13 轮（新循环第 1 轮）· REQ-FLOW：用户需求不是提示词，而是流匹配策略的条件变量——把 32 个任务的容差、评分与安全写进同一个模型

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本轮是新灵感循环第 1 轮，承接第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO。三个灵感词是「用户需求分析」「UniBot」「流匹配策略」。

## 0. 先给结论：第 12 轮把「怎么执行」做细了，却没有把「什么算够好」写进策略

第 12 轮 CHUNK-SERVO 的核心是：官方 WLA 做 30 步语义规划，33k 成功演示检索「受器→夹爪」相对目标，确定性视觉伺服每 5 步闭环一次，数字孪生只标定 RTT/增益/外参，竞赛策略按 `q_t×Δ/cost` 分配工程。它把最后 3 厘米从开环变成闭环，这是对的。

但它仍然默认了一件事：

> **32 个任务、6 个阶段，对「多准才算够」是同一个需求。**

事实不是。挂杯子允许 3–5 mm；插网线只允许 0.5–2 mm；叠毛巾根本没有毫米级目标；人为干扰时，第一需求从「完成任务」变成「别撞人、别把杯子扫下桌」。同一个固定 5 步伺服、同一组增益、同一个 1 cm/0.05 rad 限幅，等于把用户需求平均掉了。平均的结果是：紧任务不够准，松任务不必要地慢，变形任务被几何伺服带偏，人为干扰时还在追一个已经失效的目标。

所以本轮的押注是 **REQ-FLOW**：

> **用「用户需求分析」把每个任务/阶段的成功条件、容差、接触时长、安全边界和评分权重，抽成一个低维、可检查、可调的需求向量 `r`；用同一个流匹配策略在 `r` 的条件下生成「计划先验 + 残差修正」；用 `r` 决定提交时固定的 `action_chunk_size`，以及线上的 flow 步数、引导强度、计划刷新和 safe tail。仍然只有一个学习模型，需求表是配置，安全过滤是确定性控制器。**

一句话：**第 12 轮让策略每 5 步看一次世界；第 13 轮让策略先知道「这个世界要求它看到什么精度」，再决定用多少步、多大增益、多长的安全尾巴。**

三个可验证创新点：

1. **R-ELICIT（需求抽取）**：从任务几何、评分 rubric、演示统计和失败边界，离线构建 `32 任务 × 6 阶段` 的需求表；每个需求都绑定一个可观测代理（双目目标位姿、腕部图、接触距离、编辑分数）。用 G8 验证：需求类别能否预测真机/仿真的成功边界，Spearman ≥0.6；否则退回默认类别。
2. **REQ-FLOW（需求条件化残差流）**：把官方 WLA 的 DiT 扩散 action head 改为/fine-tune 成 rectified-flow matching head；流不生成整段动作，而是生成围绕「上一块计划 / 演示检索计划 / VLA 计划」的 SE(3) 残差；条件包括观测、需求 `r`、先验置信度、伺服误差。用 G9/G10 验证：N=2–4 步不劣于 4 步扩散，引导修正至少降 30% 末端误差，且不增约束违反。
3. **R2H（Requirement-to-Horizon）+ anytime 调度**：用容差-时域上界、接触带宽上界和延迟上界，离线选一个全任务共享的固定 `H_api`；在线只调 flow 步数 `N`、引导强度 `η`、计划刷新时机和 safe tail。用 G11/G12 验证：接触任务上 `H=5` 优于 `H=30`，safe tail 降低超调/超时，松任务不回归。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **用户需求分析** | 需求向量 `r`、R-ELICIT 需求表、R2H 调度、按需求重排任务组合 | 不做第二个「需求预测」学习模型；不把语言提示当成唯一需求；不假设所有任务同一容差 |
| **UniBot** | 单模型、32 任务、10 次/任务、5 类泛化、180 s、固定 chunk API、N 端口隔离 | 不假设 API 允许在线改 chunk size；不做 32 个任务各一个策略；不把榜单当难度表 |
| **流匹配策略** | rectified-flow action head、残差流、少步 ODE、解析引导、anytime early-stop | 不从零训 VLA；不默认 1 步蒸馏；不把 flow matching 当成「更大模型」的替代品 |

## 1. 直觉：为什么「用户需求分析」是执行层之后的下一个杠杆

### 1.1 用户不是语言提示，用户是评测器和它的评分表

UniBot 的「用户需求」至少有三层，而且它们不总是一致：

- **功能需求**：任务成功。插头要插进去、杯子要挂住、拉链要拉上。
- **质量需求**：步骤分、耗时、平滑度。成功率相同看总平均步骤分，再相同看更早提交；单次 180 s 超时记失败。
- **安全/鲁棒需求**：不撞桌、不扫落物体、人为干扰时能停/恢复；5 类泛化各 2 次，人为干扰占 20%。

自然语言只说了第一层的一部分：`"hang the cup"` 没有告诉你容许 3 mm 还是 5 mm，也没有告诉你接触段该降速还是该保持。演示只展示了「成功过」，没有展示「差多少会失败」。这两个信息恰好是执行层最需要的。

所以「用户需求分析」在这里不是产品文档，而是一个**可计算的需求规格**：

```text
语言/任务表  →  功能谓词、阶段、物体/受器几何
评分 rubric   →  成功/步骤/时间/安全的权重
演示统计      →  接触时长、接近速度、成功对齐误差分布
几何/仿真     →  容差边界、安全间隙
                    ↓
        r = (τ_p, τ_r, τ_s, T_c, L_res, w, κ, c_o)
```

`r` 是低维、数值化、可检查的。语言说「挂杯子」；`r` 说「位置容差 3 mm、姿态容差 4°、安全间隙 8 mm、接触段至少 2 次修正、先验置信度 0.7」。后者才能直接进控制器。

### 1.2 固定 5 步是一个折中，不是需求

第 12 轮选 5 步的理由很合理：5 步 @30 Hz = 167 ms，够接触段做 1–2 次修正，又能摊薄 VLA 推理。但它是**一个全局折中**，不是从任务需求推出来的：

- 插网线：0.5–2 mm 容差，接触窗口可能只有 0.3–0.8 s；5 步块可能只给了 2–4 次修正，仍然偏粗。
- 搬水果/整理颜色：10–30 mm 容差，30 mm/s 的残差运动；5 步块把 VLA 推理放大了 6 倍，完全没必要。
- 叠毛巾/装箱：目标不是 6D 位姿，几何伺服没有意义；5 步块只是增加了调用次数。
- 人为干扰：目标被移动后，原计划失效；此时需要的不是更高增益，而是先停、重定位、换需求。

REQ-FLOW 不假设一个固定 `H` 对所有任务最优。它把 `H` 的选择变成一个**需求驱动的离线组合优化**：接触紧任务要求小 `H`，搬运松任务允许大 `H`，延迟和调用次数给出上界；因为 API 的 chunk size 是提交时固定的，所以最终只能选一个共享的 `H_api`，但它是被需求推导出来的，不是拍脑袋的。线上再把 `N`、`η`、计划刷新和 safe tail 作为自由度。

### 1.3 为什么是流匹配，而不是「再换一个更大的扩散头」

流匹配策略的三个性质，恰好对上本轮的需求：

1. **连续时间、少步 ODE**：从噪声到动作是一条可积分的速度场；可以在任意步早停，天然适合「预算够就多算，预算不够就少算」的 anytime 执行。
2. **多模态**：接触任务的修正往往不是单峰的——孔在左还是右、从上面还是侧面绕、先抬还是先推。确定性回归会平均成「中间那条最糟的轨迹」；流匹配可以保留多个模态，再由需求 `r` 选一个。
3. **可解析引导**：我们不需要再训一个 cost model，就可以把 `-∇C` 加到 ODE 上；`C` 可以是双目目标位姿误差、安全距离、关节限位、平滑度。这使「需求」可以直接进生成过程，而不是事后 clip。

官方 WLA 的 action head 是 DiT-L 扩散头：`action_horizon=30`、`num_inference_timesteps=4`、`action_dim=54`（本轮 2026-10-31 复核 `config.yaml`）。REQ-FLOW 不是假设官方已经是 flow matching，而是把**同一个 action head** 的生成目标从扩散改成 rectified flow，并保持 VLM 冻结。这样既利用官方 6B 基座，又不引入第二个策略模型。

### 1.4 为什么是「残差流」，而不是从零生成整段动作

从零生成 30 步动作，样本空间大、模态多、容易生成「看起来像演示但不对齐当前物体」的轨迹。残差流生成的是围绕计划先验 `Ā` 的局部修正 `X`：

```text
A = Ā ∘ exp(σ(r, c_o) · X)
```

好处：

- **低方差**：`X` 只在先验附近，流的学习目标更窄；同样的模型容量可以换更细的修正。
- **时序一致**：上一块计划的尾部可以直接作为下一块的先验，块与块之间不会跳变。
- **可解释**：`X` 的大小就是「策略认为自己离先验有多远」；先验置信度 `c_o` 低时自动放大 `σ`，高时缩小。
- **可回退**：`X` 太大或需求裕度为负时，退回 CHUNK-SERVO 的解析伺服或 VLA 开环，不会因为 flow 采样坏掉而失控。

这也让「用户需求」有了一个自然的入口：`σ`、`N`、`η`、`H_tail` 都由 `r` 和 `c_o` 决定。紧容差、低先验置信度 → 小步、多步、强引导、长安全尾；松容差、高置信度 → 大步、少步、弱引导、短尾。

### 1.5 一个必须提前说的负结果：1 步流匹配会丢模态

我们在一个 1D 双峰玩具上做了 sanity check（见产物区 §8）：1 步 Euler 把所有样本压到均值 0，双峰完全消失；2 步恢复左右各 50%，4 步的组内标准差 0.29 已接近真实 0.30。这说明：

- **不能默认 1 步蒸馏**。接触任务的多模态恰恰是流匹配的价值；1 步会把「从左插还是从右插」平均成「正中间撞上去」。
- **默认 `N ∈ {2,4}`**；只有经过 G9 的模式覆盖验证，才允许 1 步。
- 这条负结果也解释了为什么第 12 轮的「确定性伺服 + 单一目标」在紧任务上会饱和：它本质上是在做一个单峰修正，而真实修正分布可能是多峰的。

## 2. 方法草图：三个组件，一个模型

### 2.1 R-ELICIT：把需求从文档/几何/演示里抽出来

离线做四件事：

1. **任务模板**：把 32 个任务映射到 7 类模板（peg-in-hole、hang、stack、fasten、deform、sort/transport、human-recover）。用关键词/任务表规则，不引入第二个学习模型。
2. **几何容差**：对有几何先验的任务，用间隙算容差。例如插孔类 `τ_p ≈ (D_hole − D_peg)/2 − δ_safe`；挂杯类用钩/杯沿间隙；叠碗用碗沿半径差；拉链/锁用齿/键的咬合深度。没有几何的，用成功演示的对齐误差高分位数 + 安全因子。
3. **动力学需求**：从演示的相位分割估计接触时长 `T_c`、接近速度、残差目标速度 `L_res`（不是机器人自身速度，而是计划解释不了的目标运动）。`L_res` 用稳健高分位数，避免被单帧噪声拉高。
4. **权重与可观测性**：从 rubric 取成功/步骤/安全/平滑权重；为每个需求绑定代理信号。目标位姿可由头双目/检索给出，接触距离可由 GEO-RESIDUAL 给出，编辑由场景残差给出；没有代理的需求标 `κ=0`，不参与在线硬判。

需求表按 `(task, phase)` 存储，规模 32×6×~16 维，随提交包分发，不是模型权重。单任务通道每测 3–5 个任务更新一次，形成「离线表 → 在线执行 → 单任务反馈」的闭环。

### 2.2 REQ-FLOW：需求条件化残差流

训练时：

```text
采样演示块 → 采样先验 Ā（上一块 / 检索演示 / 模型自身上一块 / 加扰先验 / 零先验）
           → 算残差 X = log(Ā^{-1} ∘ A_demo) / σ(r,c_o)
           → 采样 t, X0 ~ N(0,I), Xt = (1-t)X0 + tX
           → uθ(Xt, t, o, r, Ā, e) 预测 X - X0
           → 损失 = 需求权重 ω(r,A_demo) · ||uθ - (X-X0)||² + λ·barrier(Â)
```

关键设计：

- **需求加权**：`ω(r,A_demo) = exp(β_s·s(A_demo;r) + β_q·q_demo)`。成功、步骤分高、平滑、无碰撞的演示块权重大；紧容差任务的块权重大。这样同一个模型不会为了照顾松任务而牺牲紧任务。
- **先验 dropout**：训练时随机把先验换成检索段、模型自身上一块（stop-gradient）、加扰段、零段，让模型学会「先验可能错」，也覆盖推理时的自回归分布。推理时才能根据 `c_o` 自适应：先验好就小修，先验坏就大修。
- **误差条件**：伺服误差 `e`（6D 位姿误差、接触距离、编辑分数）作为条件输入，而不是事后加 `Δ`。这样流可以学到「误差大时先减速对齐、误差小时直接插入」的策略，而不是固定增益。
- **barrier**：用一步预测 `X̂₁ = Xt + (1-t)uθ` 组合出 `Â`，对关节限位、速度、工作空间、安全距离加 hinge 罚。推理时仍有确定性安全过滤，训练 barrier 只是让样本更靠近可行域。

推理时：

```text
r ← 需求表(task, phase) + 在线可观测性
Ā, c_o ← 计划缓存（上一块尾部 / 检索 / VLA）
e ← 双目/腕部/接触/编辑
N ← 调度器(r, c_o, 预算)
X ~ N(0,I)
for k = 0..N-1:
    u = uθ(X, k/N, o, r, Ā, e)
    u ← u - η·∇C(X; o, r, e)          # 解析引导，信赖域裁剪
    X ← X + u/N
    if 需求裕度 ≥ 0 且两步变化 < ε: break
A = Ā ∘ exp(σ(r,c_o)·X)
A ← Π_{S(r)}(A)                        # 安全过滤
if H_tail > 0: A[-H_tail:] ← safe_tail(A[-H_tail:], r)
return A
```

`C` 是解析代价：末端位姿误差、姿态误差、安全距离、关节/速度违反、平滑度。梯度用 URDF 运动学/有限差分算，不引入第二个网络。`η` 按 `r` 和 `c_o` 调度；紧容差、低置信度时增大，但受信赖域 `||X_{k+1}-X_k|| ≤ δ` 约束。

还可以加一个**需求 classifier-free guidance**：

```text
ũ = uθ(X,t,o,r,Ā,e) + γ·(uθ(X,t,o,r,Ā,e) - uθ(X,t,o,∅,e))
```

`γ ∈ [0,0.5]`，用来在测试时放大需求条件；紧任务调大，松任务调小。它不是必需项，但给了部署时一个不用重训的「精度旋钮」。

### 2.3 R2H + anytime 调度：需求决定 chunk，而不是反过来

因为 API 的 `action_chunk_size` 是提交时固定的，在线不能改 `H`。所以把调度拆成两层：

**提交时（离线）**：对每个任务/阶段算三个上界：

```text
容差-时域：H_tol   = max(0, floor(f_c·((τ_p - ε_flow)/L_res - τ)))
接触带宽：H_contact = max(0, floor(f_c·(T_c - τ)/m))   # m = 至少需要的修正次数
延迟：    H_lat   = max(0, floor(f_c·(B - τ - N·c_flow)))
H_t = min(H_tol, H_contact, H_lat)                     # 若 <1 则回退解析伺服
```

然后在 `H_api ∈ {3,5,8,15,30}` 上做组合选择：

```text
H* = argmin_H  Σ_t π_t·[1 - ŝ_t(H)] + λ·Latency(H)
s.t. 关键接触任务 H ≤ H_t
```

`π_t` 是任务权重（比赛里均匀 1/32），`ŝ_t(H)` 是需求满足度的离线代理。这个式子把「用户需求」直接变成了 chunk 选择：不是先选 5 再找理由，而是先算每个任务能容忍多长的开环，再选一个共享的折中。

**在线**：`H_api` 固定，只调：

- `N`：flow 积分步数，按预算和需求裕度选，`N∈{2,4,8}`；
- `η`：引导强度，按 `τ_p` 和 `c_o` 调；
- **计划刷新**：计划年龄超过 `H_api/f_c`、或编辑分数超阈值、或先验置信度掉到阈值以下，就后台刷新 VLA/检索先验；
- **safe tail**：块尾 `H_tail = ceil(v_max/(a_max·f_c))` 步进入安全集（降速/保持/回撤），保证如果下一块计划迟到，机器人不会继续冲。

这里要明确一个第 12 轮没有说透的点：**在线改 `H_api` 是不可能的**。`action_chunk_size` 在握手时固定，evaluator 按返回的 chunk 顺序执行直到下次调用。所以「5 步 vs 30 步」是提交时的实验变量，不是线上的调度变量。REQ-FLOW 把在线自由度诚实地限制在 `N/η/刷新/safe tail`，把 `H_api` 放到离线需求组合优化里。

## 3. 与第 10/11/12 轮的关系：保留、替换、剪枝

**保留**：

- 官方 WLA 6B 基座、33k 成功演示、头双目/腕部视觉、数字孪生标定、单任务不计分通道；
- FACT-VLA 的相位化 BC、GEO-RESIDUAL 的动作条件化残差/接触/编辑信号；
- CHUNK-SERVO 的演示检索相对目标、双频执行、竞赛组合、单模型合规。

**替换**：

- WLA 的 DiT 扩散 action head → rectified-flow matching action head（同一个模型，换生成目标）；
- CHUNK-SERVO 的「固定 5 步 + 固定解析伺服增益 + 事后 Δ」→「需求条件化残差流 + 解析引导 + 安全过滤」；
- 固定 `H=5` → 需求驱动的离线 `H_api` 选择 + 在线 `N/η/刷新/safe tail`；
- 任务级固定目标 → 需求级容差/安全/时间条件。

**新增**：

- 需求向量 `r`、R-ELICIT 需求表、需求加权 CFM、先验 dropout、需求 guidance、R2H 上界、safe tail、G8–G13 门。

**剪枝**：

- 不做第二个需求预测模型（需求表是规则/几何/统计，不是学习模型）；
- 不做 32 个任务各一个策略（规则禁止，且不泛化）；
- 不默认 1 步流匹配（会丢模态）；
- 不假设在线可改 chunk size；
- 不把流匹配当成「更大模型」的替代品：VLM 仍是语义/泛化的主力，flow 只负责动作生成与修正。

## 4. 可证伪的假设与门

| H1 | 需求表能预测成功边界 | G8：类别准确率 ≥70%，Spearman ≥0.6 | 退回默认需求类别；只用几何先验 |

## 5. 一句话押注与最大风险

**押注：把用户需求从语言提示里拆成可计算的条件变量 `r`，用需求条件化残差流让同一个 6B 基座在紧任务上更准、松任务上更快、干扰时更安全；用 R2H 把 `H_api` 从拍脑袋变成需求推导，用 anytime 调度把在线自由度限制在真实可变的 `N/η/刷新/safe tail`。**

**当前方案最大的风险：需求向量 `r` 的离线估计与真机成功边界不一致——如果容差/安全/接触时长估错，REQ-FLOW 会把精度和计算投到错误的地方，甚至比固定 5 步 CHUNK-SERVO 更早饱和；因此 G8 是生死门，G8 不过就退回 CHUNK-SERVO。**

### 1.2 API：chunk size 固定，chunk 内没有新观测（A）

提交模板 README（2026-10-31 复核）明确：

- `action_chunk_size`（记作 `T_a`）是每次 `get_action` 返回的动作时间轴长度，提交时固定；
- index `0` 先执行，其余按顺序执行，直到 evaluator 再次调用 `get_action`；
- 观测只有四路 RGB（`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`），没有 depth、camera_info、force/torque、tactile；
- 动作空间 `joint` / `ee` 互斥；`ee` 模式返回 `left/right_ee_pose_gripper_base` 的绝对目标位姿 `xyz+rpy`，加左右夹爪和 `pivot[7]`；
- 每次 `get_action` 都要带 `meta.token`；
- 评测跨 N 台机器人，端口从 `8765` 起连续。

**含义**：

1. `H_api` 是提交时常数，不是在线变量。第 12 轮把 `H_c` 当「提交前要扫的超参数」是对的；本轮把它进一步变成**需求驱动的离线组合优化**。
2. 在线能调的是：flow 积分步数 `N`、引导强度 `η`、计划刷新时机、chunk 内的 safe tail、以及回退策略。不能在线改 chunk 长度。
3. 没有 depth/force，意味着需求中的「位置容差、接触距离、安全间隙」必须由头双目、腕部图、演示检索和几何先验代理；不能假设有触觉。

## 2. 问题形式化

### 2.1 任务、观测、动作、chunk

设任务 \(t \in \mathcal T=\{1,\dots,32\}\)，阶段 \(p \in \mathcal P=\{\text{approach},\text{align},\text{contact},\text{transport},\text{release},\text{recover}\}\)。第 \(k\) 步观测

```math
o_k = \big(I_k^{LH}, I_k^{RH}, I_k^{LW}, I_k^{RW}, q_k, x_k^{ee}, g_k, l\big),
```

其中 \(I\) 为四路 RGB，\(q_k\) 为关节，\(x_k^{ee}\) 为双臂 EE 位姿，\(g_k\) 为夹爪开度，\(l\) 为语言。动作 chunk

```math
A=(a_1,\dots,a_H)\in\mathcal A^H,\qquad
a_h=(T_{h,L},T_{h,R},c_{h,L},c_{h,R},\pi_h),
```

\(T_{h,\cdot}\in SE(3)\) 为绝对 EE 目标位姿，\(c\) 为夹爪命令，\(\pi_h\in\mathbb R^7\) 为 pivot。\(H=T_a\) 是提交时固定的 API chunk 长度。

### 2.2 需求规格 \(r\)

定义需求向量

```math
r=(t,p,\tau_p,\tau_r,\tau_s,T_c,T_{\mathrm{rem}},L_{\mathrm{res}},c_o,\kappa,w),
```

| 符号 | 含义 | 单位/范围 |
|---|---|---|
| \(\tau_p\) | 末端位置容差 | m |
| \(\tau_r\) | 末端姿态容差 | rad |
| \(\tau_s\) | 安全间隙 | m |
| \(T_c\) | 接触阶段时长（先验/统计） | s |
| \(T_{\mathrm{rem}}\) | 剩余时间预算 | s |
| \(L_{\mathrm{res}}\) | 计划解释不了的残差目标速度 | m/s |
| \(c_o\in[0,1]\) | 先验/观测置信度 | — |
| \(\kappa\in\{0,1\}^4\) | 目标位姿/接触/编辑/时间可观测性 | — |
| \(w\in\mathbb R^6\) | 位置/姿态/安全/时间/平滑/关节权重 | — |

严格说，\(c_o,\kappa\) 是运行时上下文/可观测性，不是用户需求；这里并入 \(r\) 只为记法统一。实现上需求表只存 \(\tau_p,\tau_r,\tau_s,T_c,T_{\mathrm{rem}},L_{\mathrm{res}},w\)，\(c_o,\kappa\) 在线估计；flow 的条件实际是 \((r,c_o,\kappa,e,\bar A)\)。

\(r\) 的低维连续部分（\(\tau_p,\tau_r,\tau_s,T_c,T_{\mathrm{rem}},L_{\mathrm{res}},w\)）归一化后送入一个小的需求编码器；\(t,p\) 用类别嵌入。需求表规模为 \(32\times 6\)，是配置，不是模型权重。

### 2.3 需求满足度与可行集

给定 chunk \(A\)，取当前操作臂的末端位姿 \(T_H(A)\) 与需求目标 \(T^*(r)\)（来自演示检索/头双目/先验）；双臂任务对两臂分别计算并取较差者。定义

```math
e_p(A)=\|p_H(A)-p^*(r)\|,\qquad
e_r(A)=\|\log(R_H(A)^\top R^*(r))\|,
```

安全裕度 \(d_s(A)=\min_h \mathrm{dist}(\mathrm{FK}(A_h),\mathcal O)\)（用 URDF 正运动学映射到机器人几何），预测耗时 \(\hat T(A)\)，平滑度 \(e_{sm}(A)=\sum_h\|a_{h+1}-a_h\|^2\)。需求裕度

```math
m_p=\tau_p-e_p,\quad m_r=\tau_r-e_r,\quad m_s=d_s-\tau_s,\quad m_t=T_{\mathrm{rem}}-\hat T.
```

需求满足度（软代理）

```math
s(A;r)=\prod_{j\in\{p,r,s,t\}}\sigma\!\left(\frac{m_j}{\beta_j}\right)^{\kappa_j},
```

其中 \(\sigma\) 为 sigmoid，\(\kappa_j=0\) 时该因子取 1；\(\beta_j>0\) 是温度，按需求类配置（紧任务用更陡的曲线）。硬可行集

```math
\mathcal F(r)=\left\{A:\ m_j\ge 0\ \text{for }\kappa_j=1,\ \text{关节/速度/工作空间约束},\ \text{碰撞约束}\right\}.
```

**注意**：\(s(A;r)\) 是需求代理，不是真实任务成功。任务语义（插头是否插入、杯子是否挂住）仍由 VLA 的模仿策略和阶段/接触信号负责；REQ-FLOW 优化的是「精度、速度、安全、时间」这些可计算的需求，不声称能替代成功判定。

### 2.4 计划先验与 SE(3) 残差

计划先验 \(\bar A=(\bar a_1,\dots,\bar a_H)\) 来自三选一：

1. 上一块计划右移 \(H\) 步（receding horizon）；
2. CHUNK-SERVO 的演示检索段（目标-夹爪相对位姿/目标图）；
3. VLA 30 步计划组合成绝对 EE 后的切片。

先验置信度 \(c_o\) 由检索分数、计划年龄、编辑分数、双目内点率综合。对每条臂、每个时间步，定义残差 twist \(\xi_h=(\xi_h^p,\xi_h^r)\in\mathbb R^6\)，组合位姿

```math
T_h(\xi)=\bar T_h\exp\!\big(\Sigma(r,c_o)\,\xi_h\big),
\qquad
\Sigma(r,c_o)=\mathrm{diag}\big(\sigma_p(r,c_o)I_3,\ \sigma_r(r,c_o)I_3\big),
```

```math
\sigma_p(r,c_o)=\sigma_{p0}+\sigma_{p1}(1-c_o),\qquad
\sigma_r(r,c_o)=\sigma_{r0}+\sigma_{r1}(1-c_o).
```

平移和旋转分开缩放，避免用同一个尺度混用米和弧度。夹爪

```math
c_h(\xi)=\mathrm{clip}\big(\bar c_h+\sigma_g\,\xi_h^g,\,0,\,1\big).
```

残差轨迹 \(X=(\xi_1,\dots,\xi_H,\xi_1^g,\dots,\xi_H^g)\in\mathbb R^{H\times 14}\)。pivot 默认取先验的 \(\bar\pi\)，不进入 flow（降低维度和风险）；若 G6 证明需要，再把 pivot 加 7 维。对演示动作 \(A^*\)，残差目标为

```math
\xi_h^*=\Sigma(r,c_o)^{-1}\log\!\big(\bar T_h^{-1}T_h^*\big).
```

上式是位姿部分；夹爪残差单独定义为 \(\xi_h^{g*}=(c_h^*-\bar c_h)/\sigma_g\)，再拼成 14 维 \(X\)。

### 2.5 需求条件化残差流

令先验分布 \(p_0=\mathcal N(0,I)\)，数据分布 \(p_1(X\mid o,r,\bar A,e)\)。取线性概率路径

```math
X_t=(1-t)X_0+tX_1,\qquad X_0\sim p_0,\ X_1\sim p_1,
```

学习速度场 \(u_\theta(X_t,t,o,r,\bar A,e)\)，满足 ODE

```math
\frac{dX_t}{dt}=u_\theta(X_t,t,o,r,\bar A,e).
```

若 \(u_\theta\) 逼近边际速度 \(u_t(X)=\mathbb E[X_1-X_0\mid X_t=X]\)，则从 \(X_0\sim\mathcal N(0,I)\) 积分到 \(t=1\) 得到 \(X_1\sim p_1\)，策略输出

```math
A=\mathrm{compose}\big(\bar A,\ \Sigma(r,c_o)X_1\big).
```

### 2.6 训练目标

```math
\mathcal L(\theta)=
\mathbb E_{o,r,\bar A,A^*,e,X,t,X_0}
\left[
\omega(r,A^*)\left\|u_\theta(X_t,t,o,r,\bar A,e)-(X-X_0)\right\|^2
\right]
+\lambda\,\mathbb E\left[\sum_j\max(0,g_j(\hat A_\theta))^2\right],
```

其中

```math
\hat X_1=X_t+(1-t)u_\theta(X_t,t,o,r,\bar A,e),\qquad
\hat A_\theta=\mathrm{compose}(\bar A,\Sigma(r,c_o)\hat X_1),
```

\(g_j\) 是关节限位/速度/工作空间/安全距离的 hinge 约束。需求权重

```math
\omega(r,A^*)=\mathrm{clip}\left(\exp\big(\beta_s s(A^*;r)+\beta_q q(A^*)\big),w_{\min},w_{\max}\right),
```

\(q(A^*)\) 是演示质量（步骤分、平滑度、无碰撞）。训练时对 \(\bar A\) 做**先验 dropout**：以一定概率替换为检索段、模型自身上一块、加扰段、零先验；对 \(r\) 做**需求 dropout**（把连续需求置为默认值/加噪），使模型在需求不确定时仍能生成合理动作。VLM 冻结，只训 flow head + 需求/先验/误差编码器；初始化可复用 WLA DiT-L 扩散头骨干。

### 2.7 推理目标

从 \(X_0\sim\mathcal N(0,I)\) 出发，做 \(N\) 步引导积分：

```math
\hat X_{k+1}=X_k+\frac{1}{N}u_\theta(X_k,k/N,o,r,\bar A,e),
```

```math
X_{k+1}=\hat X_{k+1}-\frac{\eta}{N}\nabla_X C(X_k;o,r,e),
```

其中解析代价

```math
C=w_p e_p^2+w_r e_r^2+w_s\max(0,\tau_s-d_s)^2
+w_t\max(0,\hat T-T_{\mathrm{rem}})^2
+w_j\sum_j\max(0,g_j)^2+w_{sm}e_{sm}^2.
```

信赖域：若 \(\|X_{k+1}-X_k\|>\delta\)，按比例缩放回 \(\delta\)。早停：若需求裕度 \(\min_j m_j\ge 0\) 且连续两步 \(\|X_{k+1}-X_k\|<\epsilon\)，停止；若预算耗尽，输出当前样本并进入安全过滤/回退。

输出

```math
A=\mathrm{compose}(\bar A,\Sigma(r,c_o)X_N),\qquad
A^+=\Pi_{\mathcal S(r)}(A),
```

再对块尾 \(H_{tail}\) 步应用 safe tail。可选需求 CFG：

```math
\tilde u=u_\theta(X,t,o,r,\bar A,e)+\gamma\big(u_\theta(X,t,o,r,\bar A,e)-u_\theta(X,t,o,\varnothing,e)\big),
```

\(\gamma\in[0,0.5]\)，按需求强度调，不默认开启。

### 2.8 R2H 与调度

记控制频率 \(f_c=30\) Hz，观测/规划延迟 \(\tau\)，单次调用延迟预算 \(B\)。对每个任务/阶段，计算三个上界：

```math
H_{tol}=\max\!\left(0,\left\lfloor f_c\left(\frac{\tau_p-\epsilon_{flow}}{L_{res}}-\tau\right)\right\rfloor\right),
```

```math
H_{contact}=\max\!\left(0,\left\lfloor \frac{f_c(T_c-\tau)}{m}\right\rfloor\right),
\qquad
H_{lat}=\max\!\left(0,\left\lfloor f_c\left(B-\tau-Nc_{flow}\right)\right\rfloor\right),
```

其中 \(m\) 是接触段至少需要的修正次数，\(B\) 是单次 chunk 的串行周期预算（计算+执行+观测），\(c_{flow}\) 是单步 flow 计算时间。取

```math
H_t=\min(H_{tol},H_{contact},H_{lat}).
```

三个上界都先截断到非负；若 \(H_t<1\)，回退解析伺服/降 \(N\)，不要用负 horizon 去组合。

提交时在 \(\mathcal H=\{3,5,8,15,30\}\) 上做组合选择：

```math
H^*=\arg\min_{H\in\mathcal H}\ \sum_t \pi_t\big[1-\hat s_t(H)\big]
+\lambda\sum_t\pi_t\frac{T_t f_c}{H}(Nc_{flow}+\tau),
```

约束关键接触任务 \(H\le H_t\)；\(\pi_t\) 为任务权重（比赛均匀 \(1/32\)），\(\hat s_t(H)\) 是离线回放/仿真/单任务通道估计的需求满足度。网格只有 5 个点，穷举即可。

在线：固定 \(H_{api}=H^*\)，每个 chunk 选

```math
N^*=\arg\max_{N\in\{2,4,8\}}\ \hat s(r,N)-\lambda T(N),
```

其中 \(\hat s(r,N)\) 是按需求类离线标定的「N→满足度」曲线（回放/仿真/单任务通道），在线只查表，不重新采样。

并设

```math
\eta=\eta_0\cdot\mathrm{clip}\left(\frac{\tau_{p,ref}}{\tau_p},0.5,2\right)\cdot(1-c_o),
```

计划刷新条件：`plan_age > H_api/f_c` 或 `edit_score > θ_e` 或 `c_o < c_min`。safe tail：

```math
H_{tail}=\left\lceil\frac{v_{\max}}{a_{\max}f_c}\right\rceil,
```

块尾 \(H_{tail}\) 步进入安全集（降速/保持/回撤）。对接触紧任务，\(v_{\max}\) 小，\(H_{tail}\) 通常 1–2 步；对搬运松任务，\(H_{tail}\) 可能 4–8 步，但此时容差大，降速代价可接受。

## 3. R-ELICIT：需求分析算法

### 3.1 输入/输出

**输入**：

- 32 个任务的官方语言/任务说明、评分 rubric、步骤分定义；
- 33k 成功演示（视频、状态、动作、阶段标签可选）；
- 物体/受器几何（CAD/mesh/尺寸）或类别先验；
- 头双目标定、腕部相机（无内参，需一次性标定）；
- 单任务通道的 A/B 结果（用于更新）。

**输出**：需求表 \(R[t,p]=(r_{t,p})\)，每个条目包含容差、接触时长、残差速度、权重、可观测性、需求类。

### 3.2 任务模板与几何容差

把 32 个任务映射到 7 类模板；模板给出容差的几何来源：

| 模板 | 代表任务 | 容差来源 | 先验 \(\tau_p\) | 先验 \(\tau_r\) |
|---|---|---|---|---|
| peg-in-hole | PlugInEthernet、PlugCharger、ArrangeTestTubes、SyringeWaterTransfer | \((D_{hole}-D_{peg})/2-\delta_{safe}\) | 0.5–2 mm | 2–5° |
| hang | HangCup、StoreRacket、StoreEarphones | 钩/杯沿/挂点间隙 | 2–5 mm | 3–6° |
| stack | StackBowls、PaperCupStacking、StoreCups | 碗沿/杯沿半径差 | 2–6 mm | 3–6° |
| fasten | Unlock、ZipUp、OpenPillBottle | 齿/键/盖的咬合深度 | 1–3 mm | 5–10° |
| deform | FoldTowel、PackBag、PackDoll | 无严格 6D 目标；拓扑/覆盖 | 不启用 mm 级 | — |
| sort/transport | FruitSorting、ColorArrangement、ConveyorSorting、OrganizeBookshelf | 放置区域半径 | 10–30 mm | 10–20° |
| human-recover | 所有泛化轴的人为干扰试验 | 安全间隙/停止距离 | 安全优先 | — |

这些是**几何先验/示例，不是实测值**。实际值由 §3.3 的演示统计和单任务通道校准。

### 3.3 从演示估计容差、速度、接触时长

1. **阶段分割**：复用 FACT-VLA 的相位化 BC / GEO-RESIDUAL 的接触信号，或用几何启发式（夹爪到目标距离、夹爪闭合、物体运动）。每段演示切成 approach/align/contact/transport/release。
2. **对齐误差代理**：对成功演示的接触前 1–3 帧，计算夹爪轴线与目标轴线的横向距离、姿态差、以及最终放置误差。取成功分布的 90 分位 + 安全因子作为数据先验；注意这只是容差的**下界/先验**，不是容差本身——真正的失败边界要用扰动/失败数据或仿真扫边界校准。若失败演示可用，取成功/失败边界的中点。
3. **接触时长**：接触阶段持续时间 \(T_c\) 的 10 分位（保守），避免用平均时长导致紧任务修正次数不足。
4. **残差速度**：对目标/受器的在线跟踪速度减去计划预测速度，取 90 分位作为 \(L_{res}\)；没有跟踪时用任务先验（静态目标 ≈0，人为干扰 ≈0.02–0.1 m/s）。这里的 90 分位是工程先验，不是分布无关上界；安全关键任务用 99 分位/最坏情况，并由 G11 检查尾部。
5. **安全间隙**：从无碰撞演示的最小距离分布取低分位，再减安全因子；桌面/静态障碍用几何距离，动态人手用保守先验。

### 3.4 优先级与可观测性

- **硬需求**：安全、任务成功。安全约束永远硬；任务成功由 VLA 语义负责，REQ-FLOW 不直接优化。
- **软需求**：步骤分、时间、平滑度。用权重 \(w\) 进入引导代价 \(C\)，用 \(\beta_j\) 调整满足度曲线的陡峭度。
- **可观测性**：目标位姿（头双目/检索）、接触距离（GEO-RESIDUAL）、编辑（场景残差）、时间（剩余步数）。每个需求标注 \(\kappa_j\)；不可观测的需求不参与在线硬判，只作为训练先验。
- **优先级**：紧任务（R0）的需求权重高、容差小；松任务（R2）的权重低、容差大；变形任务（R3）关闭 mm 级几何需求；人为干扰（R4）把安全需求置顶。

### 3.5 需求表验证与回退

- **离线验证**：留出 session/物体/背景，检查需求类别是否能区分成功/失败边界；用仿真扰动（位置偏移、遮挡、目标移动）扫成功边界，和预测容差比较。
- **真机单任务**：每测 3–5 个任务，更新对应 `R[t,p]`；若预测容差与实测边界偏差超过一个类别，回退到默认类别。
- **门 G8**：类别准确率 ≥70%，Spearman ≥0.6；不过门则只用几何先验 + 默认类别，REQ-FLOW 退化为「任务 ID 条件化的残差流」，仍可保留 flow 的少步/引导优势。

### 3.6 代表任务的需求类（先验）

| 类 | 代表任务 | \(\tau_p\) | \(\tau_r\) | 接触 \(T_c\) | 建议 \(H\) | \(N\) | 引导 |
|---|---|---|---:|---:|---:|---:|---:|---|
| R0 紧 | PlugInEthernet、PlugCharger、ArrangeTestTubes、Unlock、ZipUp、Syringe | 0.5–2 mm | 2–5° | 0.3–0.8 s | 3–5 | 2–4（受延迟约束） | 强 |
| R1 精 | HangCup、StackBowls、PaperCupStacking、StoreCups、PackPhone、StoreEarphones | 2–5 mm | 3–6° | 0.4–1.2 s | 5–8 | 2–4 | 中 |
| R2 松 | FruitSorting、ColorArrangement、ConveyorSorting、OrganizeBookshelf | 10–30 mm | 10–20° | 0.2–0.6 s | 15–30 | 2 | 弱 |
| R3 变形 | FoldTowel、PackBag、PackDoll | 无 mm 目标 | — | — | 15–30 | 2 | 仅语义 |

**读法**：R0/R1 是 REQ-FLOW 的主战场；R2 用长 chunk + 少 flow 步摊薄推理；R3 不让几何引导压过语义；R4 先停再重定位，不追已失效的目标。

## 4. REQ-FLOW：模型与训练

### 4.1 架构

```text
四路 RGB ──► 冻结 VLM（WLA Qwen-VL）──► 视觉/语言 token
                                              │
状态/EE/夹爪 ──► state projector ─────────────┤
需求 r ──► 需求编码器 MLP ──► FiLM/AdaLN ─────┤
先验 Ā ──► 轨迹编码器（1D conv/Transformer）──┤
误差 e ──► 误差编码器 MLP ────────────────────┤
                                              ▼
                                   DiT-L flow head
                                   uθ(Xt,t,·) → 速度场
```

- VLM 冻结；flow head 复用 WLA DiT-L 的骨干（16 层、hidden 1024、32 头），输出维度改为 14 维残差/步。
- 需求编码器：2 层 MLP，输出 128 维；在 DiT 的每个 block 用 FiLM/AdaLN 注入。
- 先验编码器：对 \(H\times 14\) 的先验残差/位姿序列做 1D conv + cross-attention；也输入先验置信度 \(c_o\)。
- 误差编码器：\(e\) 为 6D 位姿误差 + 接触距离 + 编辑分数 + 夹爪状态，MLP 到 64 维，和时间步嵌入拼接。
- 输出层零初始化（或小初始化），保证训练初期速度场小、ODE 稳定；注意这不等于输出零残差（\(X_0\) 仍是噪声），需配合小 \(\Sigma\)/warmup，避免早期随机残差过大。

### 4.2 残差流的关键细节

1. **σ 缩放**：\(\sigma_p,\sigma_r\) 分别按平移/旋转缩放，\(\sigma_{\cdot 0}\) 小（如平移 0.02、旋转 0.05），\(\sigma_{\cdot 1}\) 大（如平移 0.10、旋转 0.20）。这里的 \(\sigma\) 是允许的修正尺度上限，不是典型修正幅度；先验好时模型学到的 \(X\) 会更小，先验坏时允许更大修正。
2. **先验可行性**：训练时过滤明显不可行的先验（关节限位/碰撞）；推理时若先验不可行，直接跳过残差流，回退 VLA/安全保持。
3. **信赖域/限幅**：对残差做 clip，避免单个 twist 过大；组合后再做安全过滤。
4. **多模态**：flow 的噪声 \(X_0\) 提供多模态；需求 \(r\) 通过条件选择模态。不要用确定性回归替代。
5. **时间步**：沿用 DiT 的 timestep embedding；flow 的 \(t\) 与扩散的 timestep 语义不同，初始化后需要短 warmup。

### 4.3 需求加权 CFM

- 权重 \(\omega(r,A^*)\) 只用于训练损失，不在推理时额外乘；它改变优化偏好/有效样本分布，但不改变 flow ODE 的采样形式。用重要性采样时注意方差，clip 到 \([0.1,10]\)。
- 紧任务（R0）的块权重大；松任务（R2）权重小，避免模型为了松任务牺牲紧任务。
- 失败/近失败演示（若有）可以给低权重或只用于 barrier，不直接模仿。
- 训练时对 \(r\) 做 dropout：以 10–20% 概率把连续需求置为默认值，防止模型过度依赖精确 `r`；这与推理时需求不确定相匹配。

### 4.4 先验 dropout / 误差条件

训练时先验采样分布：

| 先验类型 | 概率 | 说明 |
|---|---:|---|
| 上一块同演示 | 0.35 | 模拟 receding horizon，先验好 |
| 检索演示段 | 0.25 | 模拟 CHUNK-SERVO 检索，先验中等 |
| 模型自身上一块 | 0.1 | 模拟推理时的自回归分布；stop-gradient/DAgger |
| 加扰先验 | 0.2 | 平移/旋转/时间偏移，模拟先验误差 |
| 零/均值先验 | 0.1 | 模拟冷启动/先验失效 |

自回归先验用模型自己的上一块输出（stop-gradient），避免 exposure bias；训练早期模型太差时，先用加扰演示块过渡，再逐步提高自回归比例。

误差 \(e\) 在训练时也做增强：对成功演示注入小的位姿/接触/编辑误差，让模型学会「误差大时先对齐、误差小时直接插」。这与第 11 轮的 GEO-RESIDUAL 信号一致。

### 4.5 训练伪代码

```python
for batch in loader:
    episode, chunk, phase = sample_batch()
    r = requirement_table[task, phase]
    r = dropout_or_noise(r)

    prior = sample_prior(episode, chunk)          # prev / retrieval / perturbed / zero
    c_o = prior_confidence(prior)
    sigma = sigma0 + sigma1 * (1 - c_o)

    A_star = demo_action_chunk(episode, chunk)
    # 位姿残差 + 夹爪残差；pivot 默认不进入 flow
    X_star = concat(Sigma_inv @ log_se3(prior_pose.inverse() @ A_star_pose),
                    gripper_residual(A_star, prior))
    e = servo_error(obs, r)                        # 6D + contact + edit

    t = rand_uniform()
    X0 = randn_like(X_star)
    Xt = (1 - t) * X0 + t * X_star

    u = flow_head(Xt, t, vlm_features, r, prior, e)
    X1_hat = Xt + (1 - t) * u
    A_hat = compose(prior, Sigma @ X1_hat)
    s = requirement_score(A_star, r)
    q = demo_quality(episode)
    omega = clamp(exp(beta_s * s + beta_q * q), 0.1, 10)

    loss = omega * mse(u, X_star - X0) + lam * barrier(A_hat, r)
    loss.backward(); optimizer.step()
```

### 4.6 与 WLA 的初始化/适配

- 复制 WLA DiT-L 的 block 权重；输入/输出维度不同的层重新初始化。
- VLM 冻结；只训 flow head + 需求/先验/误差编码器（按 DiT-L 16×1024 估算约 0.3–0.4B 可训参数；以实际 checkpoint 为准）。
- 先用官方扩散头做基线，再换成 flow 目标；同一数据、同一 batch、同一评测，做配对比较。
- **动作空间/坐标帧**：WLA 原生动作是相对当前 EE 的 xyz+rotvec；挑战赛 API 的 `ee` 动作是 base 系绝对位姿。REQ-FLOW 的残差定义在「先验组合后的绝对位姿」局部切空间，因此 flow head 的输出不是 WLA 原生动作的直接替换；需要重训输出层，并在 G6 验证 EE 坐标系/TCP 偏移/夹爪方向。若帧不一致，先用 `example_env.py` 做一次手眼/TCP 校准（平移 ≤1 cm、旋转 ≤2°），否则残差会系统性偏置。
- **状态/归一化适配**：WLA 的 `robot_state_projector` 输入是 60D 状态 + 60D mask = 120D；API 只给 arm/EE/gripper/lower_body 的子集，adapter 必须按 WLA 规范填 60D、缺失模块 mask=0。动作侧 WLA 用相对 EE 的 xyz+rotvec 和全局 Z-score；REQ-FLOW 在绝对残差空间训练，不能直接复用这套归一化统计，需在 14D 残差上重新估计均值/方差，或改在相对空间预测再组合。
- 若 flow 训练不稳定：用 OT-CFM/rectified flow 的直线路径、EMA、梯度裁剪、warmup；仍不稳定则回退扩散头 + 需求调度 + 解析伺服。

## 5. 推理：anytime 引导与安全

### 5.1 引导 ODE

```python
X = randn(H, 14)
for k in range(N):
    t = k / N
    u = flow_head(X, t, vlm_features, r, prior, e)
    if eta > 0:
        g = grad_cost(X, r, e)          # 解析/有限差分
        u = u - eta * g
    dX = u / N
    if norm(dX) > delta:
        dX = dX * (delta / norm(dX))
    X = X + dX
    if margin(X, r) >= 0 and norm(dX) < eps:
        break
A = compose(prior, Sigma @ X)
A = safety_filter(A, r)
if H_tail > 0:
    A[-H_tail:] = safe_tail(A[-H_tail:], r)
```

### 5.2 早停

早停条件必须同时满足：

1. 需求裕度 \(m_j\ge 0\)（可观测项）；
2. 连续两步 \(X\) 变化小于 \(\epsilon\)；
3. 预算未超（\(N c_{flow} + \tau \le B\)）。

若只满足 1 不满足 2，继续积分以降低方差；若只满足 2 不满足 1，继续积分或增加 \(\eta\)；若预算耗尽，输出当前样本并进入安全过滤/回退。

### 5.3 安全过滤

- **凸安全集（近似）**：速度限幅、工作空间盒、桌面最小高度、已知静态障碍的保守包围盒在笛卡尔空间是凸的，投影用 \(\Pi_{\mathcal S}\)。关节限位通过 IK 可行性检查/关节空间 CBF 兜底，不并入同一个凸集投影。
- **碰撞**：对动态障碍/人手，用控制屏障函数（CBF）或简单停止；不声称对非凸碰撞有硬保证。
- **safe tail**：块尾 \(H_{tail}\) 步进入安全集；若无法满足，整块回退为保持/回撤。接触相位只做保持/微降速，不回撤；回撤只用于非接触或安全违规。
- **限幅**：单步位置/姿态修正限幅，避免 flow 输出过大；结合信赖域。

### 5.4 需求 CFG

- 训练时以 10–20% 概率把 \(r\) 置为 \(\varnothing\)（默认需求），得到条件/无条件速度场。
- 推理时 \(\tilde u=u_\theta(r)+\gamma(u_\theta(r)-u_\theta(\varnothing))\)。
- \(\gamma\) 默认 0；只在 G12 证明有效且不饱和时启用。紧任务可试 \(\gamma=0.2\)–0.3。

### 5.5 回退树

```text
if 先验不可行/缺失:
    回退 VLA 开环或安全保持
elif 目标位姿不可观测 (κ_p=0):
    回退腕部目标图 IBVS 或先验残差流（弱引导）
elif flow 置信度低 (c_o < c_min 或 连续 3 块 ||X|| > δ_max):
    回退 CHUNK-SERVO 解析伺服
elif 安全过滤不可行:
    保持/回撤，结束当前尝试
elif 延迟超预算:
    返回 safe tail / 保持
else:
    REQ-FLOW 输出
```

回退不是失败：它保证 `get_action` 永远返回合法动作；REQ-FLOW 的收益集中在 R0/R1 任务，R2/R3 回退 VLA 是预期行为。

## 6. R2H 与复杂度

### 6.1 容差-时域上界（核心）

设计划在 \(t_0\) 由观测 \(o_{t_0-\tau}\) 生成，开环执行 \(h\) 秒。设目标/受器的**残差运动**（计划解释不了的部分）是 \(L_{res}\)-Lipschitz。则末端误差满足

```math
\|e(h)\|\le L_{res}(h+\tau)+\epsilon_{flow}.
```

因此，若要保证 \(\|e\|\le\tau_p\)，一个保守充分条件是

```math
h\le\frac{\tau_p-\epsilon_{flow}}{L_{res}}-\tau,
\qquad
H_{tol}=\left\lfloor f_c\left(\frac{\tau_p-\epsilon_{flow}}{L_{res}}-\tau\right)\right\rfloor.
```

**注意**：\(L_{res}\) 不是机器人自身速度，也不是目标的总速度；它是计划预测之后剩下的、不可预测的相对运动。静态目标且计划准确时 \(L_{res}\approx 0\)，\(H_{tol}\to\infty\)（只受其他上界约束）；实现时给 \(L_{res}\) 设正下限（如 \(10^{-4}\) m/s），或当 \(L_{res}<\epsilon_L\) 时令 \(H_{tol}=\infty\)，避免除零。人为干扰/目标移动时 \(L_{res}\) 大，必须短 chunk。

更严格地说，末端误差还包含标定偏差 \(\epsilon_{calib}\) 和跟踪误差 \(\epsilon_{track}\)，它们不随 \(H\) 缩小。若 \(\epsilon_{calib}+\epsilon_{track}\ge\tau_p\)，任何 chunk 长度都无法保证容差；此时必须先重标定/降速/换代理，R2H 只解决「时域」这一项。G0/G6 负责把这两项压到容差以下。

另外，\(\epsilon_{flow}\) 是残差流在验证集上的**修正后**末端误差（含先验误差的残余），不是先验本身的误差；它由 G9/G10 估计，未过门之前不能把它当作已知常数。

### 6.2 接触带宽上界

若接触阶段持续 \(T_c\)，至少需要 \(m\ge1\) 次闭环修正，则每次修正对应一个 chunk，故

```math
m\cdot\frac{H}{f_c}\le T_c-\tau
\quad\Rightarrow\quad
H_{contact}=\left\lfloor\frac{f_c(T_c-\tau)}{m}\right\rfloor.
```

这是「接触段需要多少次看世界」的计数上界。R0 任务 \(T_c\) 短、\(m\) 大，所以 \(H\) 小；R2 任务 \(T_c\) 可忽略，约束松。

### 6.3 延迟上界

单次 chunk 的串行周期预算 \(B\)（计算+执行+观测，例如 p99 250 ms）：

```math
Nc_{flow}+\frac{H}{f_c}+\tau\le B
\quad\Rightarrow\quad
H_{lat}=\left\lfloor f_c(B-\tau-Nc_{flow})\right\rfloor.
```

如果 \(H_{lat}<3\)，说明延迟预算不足以支持当前 flow 步数；应降 \(N\)、降分辨率、或回退解析伺服。

### 6.4 提交时 H 选择

因为 \(H_{api}\) 全任务共享，不能对每个任务取不同的 \(H_t\)。用组合损失：

```math
L(H)=\sum_t\pi_t\big[1-\hat s_t(H)\big]
+\lambda\sum_t\pi_t\frac{T_t f_c}{H}(Nc_{flow}+\tau).
```

第一项是需求不满足的期望，第二项是推理/延迟开销；\(T_t\) 是任务平均时长，\(T_t f_c/H\) 是 chunk 数。约束关键 R0 任务 \(H\le H_t\)。离线 \(H_{lat}\) 用 \(N_{\max}=4\) 计算（保守），在线 \(N\) 再在剩余预算内选；若某个 \(H\) 只能配 \(N=2\) 才满足周期预算，就把它标记为「仅低 N 可用」。在 5 个候选上穷举，选最小损失。这个式子的直觉：

- 如果 R0 任务多、容差紧，第一项把 \(H\) 推向 3–5；
- 如果 R2 任务多、时长久，第二项把 \(H\) 推向 15–30；
- 比赛 32 任务均匀，且 R0/R1 占多数（第 12 轮先验 19/32 接触相关），所以 \(H=5\) 很可能是折中；但现在是推导出来的，不是拍的。

### 6.5 在线 N/η/刷新/safe tail

- \(N\)：从 \(\{2,4,8\}\) 选；紧任务/低置信度选 4–8，松任务选 2；早停可提前结束。在线选 \(N\) 时还要满足 \(Nc_{flow}+H_{api}/f_c+\tau\le B\)，否则降到可行的 \(N\) 或回退。
- \(\eta\)：\(\eta_0\cdot\mathrm{clip}(\tau_{p,ref}/\tau_p,0.5,2)\cdot(1-c_o)\)；\(\eta_0\) 是基准引导强度（如 0.1–0.3），\(\tau_{p,ref}\) 是参考容差（如 5 mm）。紧任务/低置信度大，松任务/高置信度小；上限防止引导压过先验。
- 刷新：计划年龄、编辑分数、先验置信度；后台线程，不阻塞 `get_action`。
- safe tail：按 \(v_{\max},a_{\max},f_c\) 算；块尾进入安全集。接触相位只保持/微降速，不回撤，避免把已接触的物体拉开。

### 6.6 复杂度

设 flow head 参数量 \(P_f\)（按 DiT-L 估算约 0.3–0.4B；以实际 checkpoint 为准），VLM 参数量 \(P_v\approx 6B\)（冻结），动作维 \(d=14\)，horizon \(H\le30\)，需求维 \(m\le16\)。

| 项 | 复杂度 | 说明 |
|---|---|---|
| 训练/样本 | \(O(P_f+Hd)\) + VLM 前向（可缓存） | VLM 冻结；若在线前向，\(O(P_v)\) 主导 |
| 推理/chunk | \(O(N(P_f+Hd+Hd^2))\) | 引导梯度用有限差分/URDF，\(d=14\) 很小 |
| VLM 刷新 | 每 \(H/f_c\) 秒一次 \(O(P_v)\) | 计划缓存隐藏推理 |
| 调度 | 离线 \(O(5\cdot32\cdot6)\)；在线 \(O(N)\) | 网格很小 |
| 内存 | flow head + VLM + 需求表 + 检索索引 | 无第二个模型；检索索引 <1 GB |

延迟示例（\(c_{flow}=10\) ms，\(\tau=50\) ms，\(f_c=30\) Hz）：

| \(H\) | \(N\) | 计算 | 执行 | 串行周期（不含 \(\tau\)） |
|---:|---:|---:|---:|---:|
| 5 | 4 | 40 ms | 167 ms | **207 ms** |
| 5 | 2 | 20 ms | 167 ms | **187 ms** |
| 3 | 4 | 40 ms | 100 ms | **140 ms** |
| 8 | 2 | 20 ms | 267 ms | **287 ms** |
| 30 | 1 | 10 ms | 1000 ms | **1010 ms** |

表中串行周期 = 计算 + 执行，不含观测延迟 \(\tau\)；含 \(\tau=50\) ms 时统一再加 50 ms（例如 \(H=5,N=4\) 为 257 ms）。按 G5 的 250 ms 含 RTT 周期预算，\(H=5,N=4\) 已经超预算；R0 的默认组合应是 \(H=5,N=2\)（237 ms，留 13 ms 给 RTT）或 \(H=3,N=4\)（190 ms）。表中 \(H=5,N=4\) 只作计算量示例；\(H=8,N=2\) 和 \(H=30,N=1\) 也超过 250 ms，只用于说明长 chunk 的代价。正式提交的 \(H\) 必须在离线组合优化中满足 §6.5 的周期约束。这些是设计估算，不是实测；G5 必须用单任务通道测 p99。

## 7. 正确性论证

### 7.1 假设

- **A1（流正则性）**：边际速度 \(u_t\) 在 \(X\) 上 \(L_u\)-Lipschitz 且有界；学习到的 \(u_\theta\) 有 \(L^2\) 误差 \(\le\epsilon\)。
- **A2（需求光滑性）**：约束函数 \(g_j\) 是 \(L_g\)-Lipschitz；残差目标运动是 \(L_{res}\)-Lipschitz。
- **A3（先验可行性）**：计划先验 \(\bar A\) 在硬约束内，且有正裕度 \(m_0>0\)。
- **A4（安全集凸性）**：用于投影的安全集 \(\mathcal S(r)\) 是闭凸集（速度限幅、笛卡尔盒、桌面高度）；关节限位和碰撞用可行性检查/CBF 兜底，硬保证只对这个凸子集成立。

### 7.2 命题与证明要点

**命题 1（流匹配一致性）**：在 A1 下，N 步 Euler 生成的分布 \(\hat p_1\) 满足

```math
W_1(p_1,\hat p_1)\le C_1/N+C_2\sqrt{\epsilon}.
```

证明要点：flow matching 的连续性方程保证精确速度场把 \(p_0\) 推到 \(p_1\)；Euler 离散的全局误差由 \(L_u\)-Lipschitz 和 Grönwall 给出 \(O(1/N)\)；速度场误差通过流映射的 Lipschitz 性传播为 \(O(\sqrt{\epsilon})\)。这是标准结果，常数依赖 \(L_u\) 和维数。

**命题 2（残差局部性）**：在 A2–A3 下，若 \(\|\sigma X\|\le\delta<m_0/L_g\)，则 \(A=\mathrm{compose}(\bar A,\sigma X)\) 仍满足先验的硬约束，裕度至少 \(m_0-L_g\delta\)。

证明：\(g_j(A)\le g_j(\bar A)+L_g\|\sigma X\|\le\tau_j-m_0+L_g\delta<\tau_j\)。这说明残差流围绕可行先验做小修正时不会破坏可行性；也说明 \(\delta\) 信赖域和先验质量门控是必要的。

**命题 3（容差-时域上界）**：在 A2 下，开环执行 \(h\) 秒、观测延迟 \(\tau\) 的末端误差满足

```math
\|e(h)\|\le L_{res}(h+\tau)+\epsilon_{flow}.
```

若右侧 \(\le\tau_p\)，则位置需求被保证。因此 \(H_{tol}\) 是保守充分上界。

证明：把误差分解为「计划对残差目标的预测误差」和「观测陈旧导致的残差运动」；后者由 Lipschitz 性界定为 \(L_{res}(h+\tau)\)。三角不等式合并。

**命题 4（接触带宽）**：若接触段需要 \(m\) 次修正、持续 \(T_c\)，则 \(H\le f_c(T_c-\tau)/m\)。

证明：每个 chunk 在结束时提供一次新观测/修正；\(m\) 次修正需要 \(m\) 个 chunk，总时长 \(mH/f_c\) 不超过可用接触时间 \(T_c-\tau\)。

**命题 5（安全过滤）**：在 A4 下，\(A^+=\Pi_{\mathcal S}(A)\) 满足 \(\mathcal S\) 内的所有硬约束，且对任意 \(A^*\in\mathcal S\)，\(\|A^+-A\|\le\|A-A^*\|\)。

证明：凸集投影定理；投影非扩张。关节限位、非凸碰撞约束不在这个硬保证范围内，需 IK 可行性检查/CBF/停止兜底。

**命题 6（anytime 下降）**：若 \(C\) 凸且 \(L_C\)-光滑，引导更新满足

```math
C(X_{k+1})\le C(X_k)
+\frac{1}{N}\langle\nabla C(X_k),u_\theta(X_k)\rangle
-\frac{\eta}{N}\|\nabla C(X_k)\|^2
+\frac{L_C}{2N^2}\|u_\theta-\eta\nabla C\|^2.
```

若 flow 方向与代价下降方向对齐（\(\langle\nabla C,u_\theta\rangle\le0\)），或取 \(\eta>\max(0,\langle\nabla C,u_\theta\rangle/\|\nabla C\|^2)\)（并受信赖域上限约束），则当 \(N\) 足够大时一阶项为负、二阶项 \(O(1/N^2)\) 被压住，代价下降；若 \(\nabla C=0\)，已在驻点。早停在非负需求裕度时返回可行动作（假设裕度是有效证书）。

证明：标准下降引理；把 flow 项视为一阶扰动，二阶项随 \(1/N^2\) 缩小。该命题不保证全局最优，也不保证每次单调下降；它给出的是步长/预算的定性依据。

### 7.3 单模型合规性

REQ-FLOW 的合规论证：

- **一个 checkpoint**：VLM + flow action head 是同一个 WLA 模型；flow head 是 action head 的替换，不是第二个策略。
- **需求表是配置**：\(R[t,p]\) 由规则/几何/统计生成，不含学习权重；随提交包分发。
- **调度/安全过滤是确定性控制**：R2H、早停、投影、safe tail 都没有学习参数。
- **误差/先验编码器属于同一模型**：它们和 flow head 一起训练，是 action head 的一部分，不加载外部编码器。
- **禁止项**：第二个需求预测网络、第二个残差策略、独立视觉编码器、逐任务策略。

如果官方对「模型」作最宽解释，采用 C1/C2/C3 合规模式：C1 只离线用需求表；C2 主推（确定性控制器）；C3 需要强描述子时用同一 checkpoint 的 encoder。提交材料写清楚「一个学习模型 + 一个确定性控制器 + 一张配置表」。

### 7.4 局限

- \(s(A;r)\) 是需求代理，不是任务成功判定；VLA 语义仍是成功的主力。
- 需求表可能估错；G8 是生死门。
- \(\epsilon_{flow}\) 的估计误差会直接传播到 \(H_{tol}\)；G9/G10 的置信区间要进入 R2H 的保守裕度。
- 命题 1 的误差界还包含有限数据/泛化误差；6B VLM 的视觉分布外误差不在 \(\epsilon\) 内，需 G9/G12 实测。
- 1 步 flow 会丢模态；默认 2–4 步。
- 引导不是精确条件采样；信赖域/小 \(\eta\) 是必要的。
- 安全硬保证只对凸子集；动态障碍靠 CBF/停止。
- API 的 `pivot` 语义需单任务通道验证；默认零 pivot 回退。
- 固定 \(H_api\) 不能在线变；R2H 是提交时决策。
- 需求表对未见任务可能不适用；用默认需求 + VLA 语义兜底。

## 8. 数值 sanity check（玩具，不是实验证据）

### 8.1 1D 双峰流匹配：1 步丢模态，2–4 步恢复

数据 \(p_1=0.5\mathcal N(-1,0.3^2)+0.5\mathcal N(1,0.3^2)\)，先验 \(p_0=\mathcal N(0,1)\)。用线性插值的边际速度（高斯混合的闭式速度场）做 Euler 积分，\(10^6\) 个样本：

| N | 均值 | 标准差 | 左/右比例 | 组内标准差 |
|---:|---:|---:|---:|---:|
| 1 | 0.000 | **0.000** | —（全塌缩到 0） | 0.000 / 0.000 |
| 2 | 0.000 | 0.632 | 0.500 / 0.500 | 0.311 / 0.310 |
| 4 | 0.000 | 0.880 | 0.500 / 0.500 | 0.290 / 0.289 |
| 8 | 0.000 | 0.958 | 0.500 / 0.500 | 0.290 / 0.289 |
| 16 | 0.000 | 1.000 | 0.500 / 0.500 | 0.294 / 0.293 |
| 32 | 0.000 | 1.021 | 0.500 / 0.500 | 0.296 / 0.296 |

读法：N=1 把所有样本压到均值 0，双峰完全消失；N=2 恢复双峰，但组内方差略大；N=4 已接近真实（真实组内标准差 0.30）。注意：N=1 的精确塌缩是「线性路径 + 对称高斯先验」在这个玩具里的极端表现；真实任务中 1 步未必精确塌缩，但会系统性丢模态/方差偏小，因此结论仍是「不默认 1 步」。**默认 N=2–4；1 步蒸馏必须过模式覆盖门。**

### 8.2 容差-时域上界

取 \(f_c=30\) Hz，\(\tau=50\) ms，\(\epsilon_{flow}=0\)，按 \(H_{tol}=\max(0,\lfloor f_c(\tau_p/L_{res}-\tau)\rfloor)\)：

| \(\tau_p\) \ \(L_{res}\) | 1 cm/s | 2 cm/s | 5 cm/s |
|---:|---:|---:|---:|
| 1 mm | 1 | 0 | 0 |
| 2 mm | 4 | 1 | 0 |
| 5 mm | 13 | 6 | 1 |
| 10 mm | 28 | 13 | 4 |

读法：2 mm 容差、1 cm/s 残差运动时，H 最多 4；5 cm/s 时连 1 步都保证不了——必须提高反馈频率或降低相对速度。30 步 chunk 只适合松容差/低残差运动。**这正是 R2H 要把 H 从「拍 5」变成「算出来」的原因。**

### 8.3 限制

这两个检查只验证「flow 步数会丢模态」和「容差-时域上界的量级」，不验证 6B VLA、真实接触动力学、相机标定或 RTT。它们支持设计选择，不是方案有效的证据；方案有效性必须由 G8–G13 和真机单任务通道决定。

### 9.2 仿真

- 数字孪生：G1 URDF + 头双目 + 腕部模型 + 桌面；任务族 peg-in-hole、hang/stack、zip/unlock、sort/transport、deform。
- 变量：\(H\in\{3,5,8,15,30\}\)、\(N\in\{1,2,4,8\}\)、RTT \(\{0,50,100,150\}\) ms、\(L_{res}\)、扰动（位置/遮挡/背景/目标移动/人手）。
- 指标：成功率、末端误差、收敛时间、超调、约束违反、p99 延迟、恢复率。
- 用途：找稳定域和相对排序，不预测真机绝对成功率。

### 9.4 全量

- 32 任务 × 10 次；N 端口连续；每端口独立 `reset()`；监控 p99、timeout、内存、端口串扰。
- 门：无串扰、reset 干净、内存不涨、p99 可接受、无非法动作。

### 9.5 消融

1. 需求条件 \(r\) vs 任务 ID vs 无需求。
2. 残差流 vs 全动作流 vs 扩散头。
3. \(N=1/2/4/8\)；1 步蒸馏是否丢模态。
4. 引导 on/off；\(\eta\) 调度。
5. 先验 dropout on/off；先验质量。
6. R2H 的 \(H=5\) vs \(H=30\)；safe tail on/off。
7. 需求 CFG \(\gamma=0/0.2/0.3\)。
8. 安全过滤 on/off（只用于分析，不用于正式提交）。

### 9.6 门 G0–G13

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | 腕部相机能否标定？ | 重投影 ≤5 px；头双目 ROI 有效 ≥70% | 只用头双目 PBVS；腕部仅 2D 粗对齐 |
| G1 | 演示检索是否可信？ | top-5 几何有效 ≥80%；相对位姿 ≤5 mm/2° | 改用任务级固定先验 |
| G2 | 仿真伺服/流是否收敛？ | 横向 ≤2 mm、深度 ≤3 mm、2 s ≥95%；RTT 0–150 ms 稳定 | 降增益/加 H；只做 PBVS |
| G3 | 真机单任务是否涨点？ | 3/5 任务方向为正；5 任务合并 +10pp；FoldTowel 不回归 | 不提交 flow 版本 |
| G4 | 人为干扰能否恢复？ | 检测 ≤200 ms；仿真恢复 ≥70% | 只做离线标注/不线上触发 |
| G5 | 延迟是否可接受？ | chunk 周期 p99 ≤250 ms（含 RTT）；timeout 不升 | 加 H/降 N/降分辨率/关引导 |
| G6 | 32 任务干跑是否稳定？ | N 端口隔离、reset 干净、内存不涨 | 回退基线 |
| G7 | 消融是否支持因果？ | 残差/需求/引导/H 各自有效 | 保留有效部分，砍无效部分 |
| G8 | 需求表能否预测成功边界？ | 类别准确率 ≥70%；Spearman ≥0.6 | 退回默认类别/只用几何 |
| G9 | flow head 是否不劣于扩散？ | MSE ≤1.1×；模式覆盖 ≥80%（两模式各≥30%样本，组内 std ≤1.2×真实）；N=2–4 | 保留扩散头；只做需求调度 |
| G10 | 引导是否降误差不增违反？ | 末端误差 −30%；约束违反不升 | 降 η/只做安全过滤 |
| G11 | R2H/safe tail 是否有效？ | 接触 +10pp；超调/超时 −20% | 回退固定 5 步 |
| G12 | 需求条件化是否有效？ | 紧任务 +10pp；松任务不回归 >5pp | 去掉 r，只保留任务 ID |
| G13 | 单模型合规/审计 | 一个 checkpoint；无第二策略；配置表可检查 | 回退 C1/C2 合规模式 |

### 9.7 统计

- 320 trials 下 \(p\approx0.25\) 的单次标准误约 2.4pp；不要用 +1–2pp 做结论。
- 配对 A/B 的方差取决于任务内相关；报告配对差值的 bootstrap 95% CI。
- 单任务 5 次只看方向；正式结论用 10 次/任务 + 重复 session。
- 需求表的离线指标按 session/物体/背景分组，不随机切帧，避免泄漏。

## 10. 竞赛策略

### 10.1 需求感知的失败分诊

| 需求类 | 典型任务 | 主要失败 | 该投什么 | 不该投什么 |
|---|---|---|---|---|
| R0 紧 | PlugInEthernet、PlugCharger、ArrangeTestTubes、Unlock、ZipUp | 横向错位、卡住、未咬合 | 短 H、N=2–4（受延迟约束）、强引导、safe tail | 更大 VLA、更多语义数据 |
| R1 精 | HangCup、StackBowls、PaperCupStacking、StoreCups、PackPhone | 碰杯沿、掉、叠歪 | 中 H、残差流、接触相位 | 30 步开环 |
| R2 松 | FruitSorting、ColorArrangement、ConveyorSorting、OrganizeBookshelf | 抓错、放偏、背景 | 长 H、少 N、VLA 语义 | 毫米级几何伺服 |
| R3 变形 | FoldTowel、PackBag、PackDoll | 遮挡、形状、语义 | VLA + 语义需求；关闭 mm 引导 | 6D 位姿网络 |
| R4 干扰 | 人为干扰 2/10 | 目标被移动、碰撞 | 停/重定位/恢复；安全优先 | 固定轨迹、高增益追 |

### 10.2 任务组合与优先级

```text
priority_t = q_t · Δ_t / cost_t
```

- \(q_t\)：失败发生在最后 3 cm/接触段的比例（先用语义先验，单任务通道后更新）；
- \(\Delta_t\)：REQ-FLOW 在该任务上的需求增益（G8/G10/G11 的 A/B）；
- \(cost_t\)：需求表/标定/调参成本。

先做 R0/R1 中 `q_t` 最高、`cost_t` 最低的 4 个：PlugInEthernet、HangCup、ZipUp、StackBowls，再加 FoldTowel 作 R3 对照。不要一次铺 19 个。

### 10.3 预算与时间表

| 阶段 | 时间 | 交付 | 退出条件 |
|---|---:|---|---|
| P0 基线/接口 | 1 周 | WLA + API adapter；token/pivot/chunk 验证 | 单任务通道跑通 1 任务 |
| P1 需求表/标定 | 2 周 | R-ELICIT；腕部标定；目标库 | G0/G1/G8 |
| P2 flow 头/仿真 | 2–3 周 | flow head 训练；N/H/η 扫描；扰动套件 | G2/G9/G10 |
| P3 集成/单任务 | 2 周 | 残差流 + 引导 + safe tail；5 任务 A/B | G3/G5/G11/G12 |
| P4 全量干跑 | 1 周 | 32×10 干跑；N 端口；p99/内存 | G6/G13 |
| P5 提交 | 1 周 | 提交包、合规说明、回滚开关 | G7 + 全部门 |

**算力**：1×24GB GPU 训练/单端口；1×40/80GB（可选）多端口共享；16–32 CPU 核做需求表/检索/回放；存储 1–2TB 视频缓存，关键帧可降到 <100GB。

### 10.4 提交节奏

1. **W0**：官方 WLA + API adapter + 扩散头基线；单任务通道跑 1 个 R0 任务，验证 `pivot`/token/chunk。
2. **W1**：若允许多次提交，先交安全基线，锁「更早提交」tie-break。
3. **W2–W4**：需求表、flow 头、引导、safe tail；单任务 A/B。
4. **W5**：H/N/η 扫描；32 任务干跑。
5. **W6**：最终提交；保留回滚开关。

若只允许一次提交：跳过 W1，W5 后再交；不要用正式 320 trials 做未验证的 A/B。

## 11. 风险与合规

### 11.1 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 需求表估错 | H/精度投错，紧任务饱和 | G8 生死门；几何先验；默认类别；单任务通道更新 |
| 相位估计错误 | `r` 选错，紧/松需求错配 | 相位置信度进入 \(c_o\)；相邻相位需求插值；低置信度用最保守需求；G8/G12 |
| flow 头训练不稳定 | 不如扩散头 | OT-CFM/rectified flow、EMA、warmup；回退扩散头 + 需求调度 + 解析伺服 |
| 1 步丢模态 | 接触任务撞中间 | 默认 N=2–4；模式覆盖门；不默认蒸馏 |
| 残差流继承先验错误 | 修不回来 | 先验 dropout、\(c_o\) 条件、置信度低时放大 \(\sigma\)/回退 |
| 引导偏离流形 | 动作不自然/超调 | 信赖域、小 η、最后几步引导、安全过滤 |
| 安全集非凸 | 碰撞无硬保证 | 凸内近似 + CBF/停止；不声称 100% |
| 单模型解释 | 被判第二个模型 | 一个 checkpoint；需求表配置；确定性控制器；C1/C2/C3 材料 |
| 延迟/多端口 | p99 超时、串扰 | 计划缓存、异步、共享模型、每端口隔离、p99 干跑 |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组；相邻帧不跨 split |
| `pivot` 语义不一致 | 动作被拒/机器人不动 | 单任务通道验证；零 pivot 回退 |
| 需求表过拟合 32 任务 | 未见任务退化 | 需求 dropout、默认 r、连续参数化、VLA 语义兜底 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验 |

### 11.2 单模型合规审计清单

- [ ] 只有一个 checkpoint（VLM + flow head）；没有第二个策略/残差网络。
- [ ] 需求表是 `yaml/json` 配置，不含学习权重；可人工检查。
- [ ] flow head 是 action head 的替换，不是并行策略；VLM 冻结。
- [ ] 误差/先验编码器与 flow head 同属一个模型，不加载外部 encoder。
- [ ] 调度器/安全过滤/投影/safe tail 都是确定性代码。
- [ ] 没有逐任务权重/逐任务策略；需求条件通过共享 `r` 实现。
- [ ] 提交材料写清「一个学习模型 + 一个确定性控制器 + 一张需求表」。

### 11.3 最大风险一句话

**当前方案最大的风险是需求向量 `r` 的离线估计与真机成功边界不一致：如果容差/安全/接触时长估错，REQ-FLOW 会把精度和计算投到错误的地方，甚至比固定 5 步 CHUNK-SERVO 更早饱和；因此 G8 是生死门，G8 不过就退回 CHUNK-SERVO。**
