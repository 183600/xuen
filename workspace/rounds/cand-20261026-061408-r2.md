# 第 8 轮 · TERRA-CO：微调落到桌面地形，用户共创变成纠错数据，地形适应做成几何侧车

> 检索/复核日期：**2026-10-26（UTC）**。赛事身份确认：用户所指是宇树科技 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、5 类泛化场景、通才单模型赛道、选手自部署 + 官方远程真机 API 评测；不是 2026-10-22 发布的另一个“世界物理 AI 大赛”（八大赛道，含田径/格斗/任意移动），两者不要混。本轮三个灵感词是「微调」「用户共创」「地形适应」。文中 `[S…]` 来源编号与产物区 §16 的完整链接表对应；正文关键处保留了一手页面/论文名。我先做三件不讨喜但必须做的事：① 纠正“榜首 29.7%”的前提——那是 `gen_leaderboard.py` 生成的占位数据，真实榜单仍写着「即将发布」；② 把 UniBot 的规则读到手——每任务 10 次、5 类泛化各 2 次、单次 180 秒、**总平均成功率是第一排序键，步骤分只在成功率相同时作 tie-break**；③ 把「地形适应」从腿足地形翻译成**桌面地形/场景几何**，否则它不在评分轴里。然后给出本轮主判断：**不换底座、不从零训，直接用官方 UnifoLM-WLA-1.0-Base + 官方微调代码，把研究火力放在“终端加权微调 + 用户共创的桌面地形/纠错数据 + 第 4 路立体相机的几何侧车”上；这是从“推理脚手架”转向“数据-微调飞轮”的一轮。**

## 0. 本轮先核实：八个事实，第一个推翻用户前提

### 0.1 “榜首 29.7%”是占位数据，不是真实 UniBot 榜单

我抓了 `leaderboard.html`、`leaderboard_data.json` 和 `runs.html`（[S2][S3][S4]）：

- `leaderboard.html` 仍显示「即将发布 / Coming Soon」；`runs.html` 同样。
- `leaderboard_data.json` 第一行是 `"generated_from": "gen_leaderboard.py"`；8 个模型 × 32 任务 = 256 条 `task_metrics` 是脚本生成的；详情页的视频占位说明写着「测试视频占位，后续可替换为真实视频文件」。
- 因此 29.7%、28.5%、27.9% 这组数字只能当 UI 演示/难度先验，**不能用来判断谁强谁弱，也不能用来推断“头部方案”**。真实榜单发布后，本轮所有排名假设必须重跑。

这不是抠字眼：如果按“榜首不到 30%”去定目标，会把资源错配到“抠 2–3pp”；而真实的通才天花板要从外部真机榜单估。

### 0.2 参赛手册给出了决定性的排名规则

英文手册与中文手册（[S5][S6]）都写明：

- **每个任务执行 10 次独立运行**；10 次覆盖 5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰），**每类各 2 次**。
- 单次真机执行最大 **180 秒**；超时记失败，并按执行情况计算步骤分。
- 通才赛道必须一个模型完成全部 32 个任务；**不允许混合多个模型**；不限制模型架构（World Model、VLA 均可）。
- 排名：**先按 32 任务总平均成功率排序；成功率相同才看总平均步骤分；仍相同则提交日期早者靠前**。

这意味着两件事：

1. **步骤分不是和成功率并列的目标，只是 tie-break**。第 7 轮把“终局步骤占 39.8% 步骤分”当作主论据，方向没错（终局是成功闸门），但“为步骤分优化”本身价值很低；SSG 应退回“内部状态/恢复/验证”的角色。
2. **评测总量是 32 × 10 = 320 个 episode**，不是 32 个。下面的统计功效会说明：320 次只能可靠分辨“大效应”。

### 0.3 320 次评测的统计功效：+3pp 是噪声，+15pp 才勉强可辨

按 p≈0.3 估算：

```text
SE = sqrt(0.3 × 0.7 / 320) = 2.56pp
95% CI ≈ ±5.0pp
```

两独立比例、双侧 5%、80% power 的近似样本量：

| 真实提升 | 每组所需 | 总所需 | 320 次是否够 |
|---:|---:|---:|---|
| +5pp（0.30→0.35） | ~1374 | ~2748 | 远远不够 |
| +10pp（0.30→0.40） | ~353 | ~706 | 不够 |
| +15pp（0.30→0.45） | ~160 | ~319 | 刚好 |

结论：**第 7 轮“+3pp 约 80% 概率排名更高”的说法不严谨，应撤回。** 在官方 320 次评测里，只有 ~15pp 级别的差异才有 80% power；per-task 只有 10 次，SE≈14.5pp，几乎不能用于单任务归因；per-axis 只有 64 次，SE≈5.7pp。策略含义：**只做大杠杆，不做 2–3pp 的微调；离线 A/B 要配对（同 episode/同种子）才能看小效应，官方跑只看大效应。**

### 0.4 官方 WLA-1.0-Base 与官方微调代码已经可用

- `UnifoLM-WLA-1.0-Base`：6B、Apache-2.0、约 12.5GB checkpoint；官方 README 明确给出 **单卡 24GB 微调**、冻结 VLM、只训 action expert（DiT-L）+ robot-state projector；也给出 **LoRA** 配置（VLM 和/或 action model 均可 LoRA）[S13][S14][S15][S16]。
- 配置：`action_dim=54`、`action_horizon=30`、`num_inference_timesteps=4`、`image_size=[336,448]`、`target_fps=30`；默认输入 **3 路图**：`head_stereo_left` + `wrist_left` + `wrist_right` [S14][S15]。
- 官方没有发布逐任务成功率；第三方评测也指出“no published success rates”。所以它是一个强先验，不是已证实的 UniBot 基线；必须自己微调 + 真机验证 [S17][S39]。

这直接改变第 7 轮的路线：**不要从零搭 GPR-VLA；用官方底座 + 官方微调脚本，把创新放在数据、目标和几何上。**

### 0.5 UniBot 数据集 schema 与 WLA 微调配置几乎逐字段对齐

`G1_Dex1_HangCup/meta/info.json`（[S11][S12]）实测：

- 1,043 episodes / 194,564 frames / 30fps；四路相机 `head_stereo_left/right` + `wrist_left/right`；LeRobot v3。
- **动作里已有 `action.left_ee_pose_gripper_base` / `right_ee_pose_gripper_base`（6D xyz+rpy）、`action.left_gripper` / `right_gripper`、`action.waist_action_joint`、`action.base_command`、`action.left_leg` / `right_leg`**；状态里也有对应的 EE pose、waist、legs、`lower_body`。
- 官方 `unitree.yaml` 正好使用这些键（`head_stereo_left` + 两路 wrist；EE pose 动作；waist/legs/base）[S15]。这意味着：**微调不是“改架构”，而是“改数据路径 + 改损失权重 + 改采样”。** 这是本轮最重要的工程事实。

### 0.6 第 4 路相机是“白送”的几何传感器

WLA 只用 3 路图（左高 + 两腕）；UniBot API 给 **4 路**（`cam_left_high`、`cam_right_high`、两腕）[S9]。数据集里左右高是**已校正的立体对**（`head_stereo_left/right`，rectified）[S11][S12]。

→ 右高相机可以不进 VLA，而是做 **Stereo-Terrain Sidecar（STS）**：立体深度 → 桌面平面 → 容器/目标 6D 位姿 → 规范桌面坐标系。它不改变 WLA 的 3 视图输入，不重训，纯几何；正好服务第 7 轮的放置目标（PGL/OPT）与落点闭环（SVL）。这是“地形适应”在 UniBot 里最自然的落地。

### 0.8 纠错/部署数据是 2026 年真机提升的最大单一杠杆

公开证据链（全部真机/真机 benchmark）：

- **LoopWAM**（arXiv 2610.18873）：世界-动作模型 + 自身/其他策略的部署 rollout + 质量加权；Table30 V2 三轮 **23.67% → 28.00% → 37.67% → 43.33%**，+19.7pp，score 56.80，排名第一 [S20]。
- **PACER**（arXiv 2610.19248）：过程感知的纠错重加权；UR5e 拆解 87/100 vs vanilla post-SFT 54/100，**+33pp**；选中配置明显偏向“terminal-region / stop-signal”证据 [S24]。
- **DexHiL**（arXiv 2603.09121）：人机回环 post-training，**比纯离线微调平均 +25%** 成功率 [S25]。
- **Hand-in-the-Loop**（arXiv 2605.15157）：无缝干预纠正；用干预数据微调比用遥操作数据平均 **+19%**，takeover jitter −99.8%，grasp failure −87.5% [S26]。
- **BORA**（arXiv 2605.30226）：每任务仅 20 条在线轨迹，标准物体 **60.8%→82.5%**，held-out 物体 **52%→70%** [S27]。
- **Rho**（arXiv 2609.38164）：约 **15 条纠错 episode** 即可适配冻结 flow-matching 策略 [S28]。
- **FlowDAgger**：少量人类干预，在 latent space 学一个轻量策略去“转向”冻结基座，保留预训练先验 [S29]。

这条证据链的共同结论：**不是“再训一个更大的 VLA”，而是“把失败/纠错/部署 rollout 变成高质量监督”。** 这正是「微调」+「用户共创」的交点。

## 1. 三个灵感词，各自钉到 UniBot 的事实上

### 1.1 微调：不是从零训，是“官方底座 + 终端加权 + 纠错数据”的三段式

第 7 轮的隐含路线是“GPR-VLA 主干 + WLA 底座 + 大量新增模块”。本轮把它修剪成：

```text
Stage 0  Schema SFT：官方 3.3–3.9 万（collection 页面在更新，以实际下载为准），冻结 VLM，只训 action expert + state projector
Stage 1  Terminal-Weighted SFT：终端放置/插入/闭合段加权 + 放置位姿辅助头
Stage 2  Terrain SFT：2.5D 桌面地形增广 + 一致性正则
Stage 3  Correction SFT：用户共创的干预/纠错数据，结果/过程加权；LoRA 防遗忘
Stage 4  Deployment Flywheel：调试槽/自采 rollout → 质量标注 → 回到 Stage 3
```

为什么不是“全参微调 VLM”：官方默认 24GB 只训 action expert；VLM 是 Qwen3-VL 级强先验，32k 数据全参微调容易破坏空间 grounding。先用冻结 VLM + action expert 拿到可靠基线；只有在“背景/未见物品”轴上明显欠拟合时，才开 VLM LoRA（rank 8–16，多卡）。

### 1.2 用户共创：不是问卷，是“桌面地形卡 + 干预/纠错 episode”的数据引擎

UniBot 的“用户”有三层，别混：

- **评测中的人为干扰者**：官方 `human_1_note` / `human_4_note` 已经给出逐任务剧本（平移、撤销、拉上再拉开、拧回瓶盖等）[S2 的任务 info.json]。这是“用户”最直接的含义。
- **我们自己的非专家操作者**：学生/实验室同伴，按“地形卡”摆场景、按剧本干扰、在失败时接管纠正。他们不是遥操作专家，但能提供**分布外场景 + 纠错动作**。
- **评委/平台**：不计分单任务调试槽 + 计分跑，是最终“用户”。

落到产物：**TERRA-CO（Terrain Card + Correction）**。

- **Terrain Card**：一个 YAML/JSON 规格，描述桌布颜色/纹理、灯光、物体初始位姿、干扰物、容器变体、未见物品替换、人为干扰剧本、成功谓词。用户按卡摆场景；系统负责记录、校验、覆盖矩阵。
- **Correction Episode**：策略跑 → 用户判断失败 → 接管/共享控制纠正 → 记录完整 rollout（自主段 + 干预段 + 结果）。用 HandITL/DexHiL 式的“无缝接管”，避免手势跳变。
- **覆盖矩阵**：32 任务 × 5 轴 × 2 次 = 320 个评测条件；优先覆盖 12 个高价值任务（T07/T10/T13/T19/T20/T21/T23/T25/T26/T27/T31/T32）+ 8 个长程任务（T16/T17/T18/T28/T29/T30 等）。首轮 100–200 张卡、300–600 条 episode 即可，不追求“大”，追求“打在评分轴上”。
- **合规开关**：官方手册只说“每队可获得 32 任务全部真机数据用于训练与调试”，**没有明确说是否允许自采/外部数据**。默认 `external_lab_data=false`：共创数据只用于验证、失败分析、课程设计；发邮件 `challenge_support@unitree.com` 确认后，才并入训练。若不许可，退化为“2.5D 编辑 + 官方数据加权”，不碰外部真机数据。

### 1.3 地形适应：UniBot 没有腿足地形，只有“桌面地形/场景几何”

必须把话说死：UniBot 的 5 类泛化是位置、干扰物、桌面背景、未见物品、人为干扰；**没有上下坡、碎石、楼梯这类腿足地形**。如果按字面做腿足地形适应，既不在评分轴，也没有接口/数据，直接砍。

本轮把「地形适应」定义为四层“桌面地形”：

| 层 | 内容 | 对应评分轴 | 我们的手段 |
|---|---|---|---|
| 视觉地形 | 桌布颜色/纹理、灯光、背景 | 桌面背景 | 2.5D 增广 + 一致性正则 |
| 几何地形 | 桌面高度/倾斜、相机位姿、容器位置/朝向 | 位置（部分）+ 跨机器人 | 立体侧车 + 规范桌面系 |
| 语义地形 | 未见物体、同类不同外观、干扰物 | 未见物品 + 干扰物 | 地形卡 + 资产替换 |
| 动态地形 | 人移动物体、撤销步骤、拉上再拉开 | 人为干扰 | 官方备注剧本 + 纠错数据 |

一句话：**“地形适应”不是加一个腿足模块，而是让策略在“桌面几何/视觉/语义/动态”四层变化下，仍然把同一套动作跑到终局。** 其中几何层用第 4 路立体相机做，视觉/语义层用共创地形卡做，动态层用干预/纠错数据做。

## 2. 榜单头部：先拆掉假前提，再用真实代理分析

### 2.1 假前提：占位榜单不能分析“头部方案”

### 2.2 真实代理：RoboChallenge Table30 / Table30 V2

用真实真机榜单看“通才天花板”和“头部做法”（[S18][S19][S40]）：

- **专才头部**：Era0 64.33%、DM0 62.00%、GigaBrain-0.1 51.67%、Spirit-v1.5 51.00%、pi0.5 42.67%、WALL-OSS 35.33%、pi0 28.33%、X-VLA 21.33%、GR00T 14.33%。

### 2.3 头部四类做法与各自瓶颈

| 方案家族 | 公开最好成绩（代理） | 做法 | 可借鉴 | 不可照搬 |
|---|---|---|---|---|
| Era0/Robotera | Table30 专才 64.33% | 大规模数据 + 课程 + 任务专精；双臂 72.5–80%、变形物 43.3%、长程 63.3% | 数据覆盖、长尾课程、双臂协调 | 专精 + 闭源；UniBot 是通才单模型 |
| DM0.5/Dexmal | Table30 V2 通才 43.0% | Gemma3 4B + 680M action expert；60s 历史记忆；11 种自回归辅助任务；动态动作匹配；开源微调 | 小底座 + 强动作头、历史记忆、辅助任务、高效微调 | 需要大量数据/算力；记忆模块要自己接 |
| LoopWAM | Table30 V2 通才 43.33% | 世界-动作模型；自身/他人部署 rollout；质量加权；三轮 23.67→43.33 | **部署飞轮、混合质量数据、质量加权** | 世界模型训练成本高；UniBot 调试槽有限 |
| KDDI VLA-DM0.5 | Table30 V2 40.67% | 多 VLA 知识集成/动作预测融合 | 集成/蒸馏的思路 | **UniBot 明确禁止混合多个模型** |
| pi0.5 | 专才 42.67% / 通才 17.67% | 强通用 VLA 底座 | 通用先验 | 通才惩罚非常明显 |
| GR00T | 专才 14.33% | 人形通用底座 | 人形先验 | 目前真机操作仍弱 |

**头部瓶颈的共识**：

1. **通才惩罚**：专才 64% → 通才 45%，掉约 19pp；多任务相互干扰、长尾任务拖平均。
2. **长尾接触丰富/变形物**：折毛巾、拉拉链、注射器、插头、耳机盒；这些恰好是 UniBot 的 Hard/Medium 任务。
3. **场景/位置/背景漂移**：视觉编码器容易记实验室背景；UniBot 的 5 轴里 3 轴直接打这个。
4. **人为干扰/恢复**：多数模型没有“被撤销后重做”的训练；UniBot 有 2/10 次人为干扰。
5. **终局放置**：成功=所有步骤完成；最后一放/一插/一合是闸门。
6. **评测噪声**：320 次只能看大效应；单次榜单有很大的运气成分。
7. **单模型约束**：不能像 KDDI 那样 ensemble；必须在单 checkpoint 内做“内部专精”。

### 2.4 我们的攻击面：不打“更大”，打“更对”

- 对 **通才惩罚/长尾**：用 WLA 的 64 任务、2500h 先验，不跟 Era0 拼专精数据；用终端加权 + 长尾过采样把平均分拉起来。
- 对 **场景/位置/背景**：2.5D 地形卡 + 立体几何规范化；不改 VLM 也能提升。
- 对 **人为干扰/恢复**：用户共创的干预/纠错数据 + 恢复门；这是最容易被忽视、也最契合「用户共创」的轴。
- 对 **终局放置**：终端加权 + 放置位姿辅助头 + STS/OPT/SVL。
- 对 **噪声**：只做大效应；离线配对实验；官方跑不追 2–3pp。

## 3. 主判断：从“推理脚手架”转向“纠错-地形微调飞轮”

### 3.1 一句话

**把官方 WLA-1.0-Base 当发动机，把用户共创的桌面地形/纠错数据当燃料，用“终端加权 + 纠错加权”的参数高效微调把成功率的闸门（终局放置 + 抗干扰）抬起来；立体几何侧车负责最后 3 厘米，SSG/PGL/OPT/SVL 从“主武器”降为“推理护栏”。**

### 3.2 为什么这比第 7 轮更该做

- 第 7 轮把“终局放置”找对了，但主武器是推理期脚手架（PGL/OPT/ICR/SVL），没有回答“模型本身怎么变强”。官方微调代码 + 3 万+ 数据 + 24GB 门槛，使“模型变强”第一次变得便宜。
- 2026 年真机证据一致指向“数据/纠错/部署 rollout”而不是“再大一圈的 VLA”：LoopWAM +19.7pp、PACER +33pp、DexHiL +25%、HandITL +19%、BORA +21.7pp、Rho 15 条纠错。
- 排名只看成功率，且 320 次只能看大效应；把资源压在“终端 + 干扰 + 场景”三个大头上，比在单个泛化轴上抠点更符合统计现实。
- 单模型约束排除了 ensemble；但“一个 checkpoint + 多个辅助头 + 确定性几何”仍然合规，且能吃掉 KDDI 式集成的一部分收益。

### 3.3 与第 7 轮的关系

| 关系 | 内容 |
|---|---|
| 保留 | SSG（改为内部状态/恢复）、PGL、OPT、SVL、NRB 的官方备注剧本、DebugLoop、TLE/ACP/GF（收窄为地形增广） |
| 升级 | NRB → TERRA-CO 共创纠错库；L2L → 用户共创工作室；DebugLoop → 部署飞轮；WLA 底座 → 官方微调主线 |
| 新增 | TW-SFT（终端/结果加权）、STS/CP（立体地形侧车 + 规范放置）、RG（恢复门）、XSM（跨 episode 成功记忆，观察项） |
| 降级 | SSG 不再为步骤分优化；世界模型裁判降为可选辅助；TCLB 只做离线相对比较 |
| 砍 | 从零 GPR-VLA、每任务 LoRA、全 32 任务高保真孪生、自由仿真数据、运行时 MPC/仿真 RL、FLEET“第六轴”、布料/拉链/透明全物理 |

## 5. 本轮最值得做的三件事

### 5.1 TW-SFT：终端加权 + 结果加权 + 三个辅助头

- 终端段定义：episode 最后 20–30%，或最后一次夹爪张开前 1–2 秒；放置/插入/闭合任务的终端段加权更高。
- 损失：`w = 1 + α·terminal + β·placement + γ·intervention`；`L_action` 用 Huber；`L_place` 回归容器系释放位姿；`L_prog` 做步骤完成 BCE；`L_int` 做干预检测 BCE。
- 证据：PACER 的 terminal-region 选择、DexHiL 的 intervention-aware sampling、HandITL 的干预数据增益。
- 可证伪：若调试槽里终端步提升 <5pp，回退到普通 SFT + SVL。

### 5.2 TERRA-CO：100–200 张地形卡 + 300–600 条纠错 episode

- 5–10 名非专家用户，每人 10–20 张卡；覆盖 5 轴；优先 12 高价值 + 8 长程任务。
- 每张卡 1–3 条 episode；纠错 episode 单独标注“干预段/恢复结果/失败原因”。
- 质量门槛：场景真实、标签正确、动作平滑、无安全事件；拒绝率 >20% 停采。
- 合规：默认不并入训练；先用于验证/课程设计；邮件确认后再开。

### 5.3 STS/CP：用第 4 路相机做“最后 3 厘米”

- 右高 + 左高组成已校正立体对；低分辨率 SGBM/IGEV（240×320）→ 深度 → RANSAC 桌面平面 → 容器/目标 6D 位姿。
- 规范桌面系：原点在桌面/容器中心，z 向上；把 EE 动作、OPT 释放位姿、SVL 稳定性都放到这个系里。
- 频率：2–5Hz + 缓存；失败回退到标称桌面系；透明/反光物体用腕部相机/边缘兜底。
- 合规：经典几何，不算第二个学习模型；若用 FoundationStereo/FoundationPose，需披露并确认是否违反“单模型”。

## 1. 三个必须先纠正的前提

### 1.1 “榜首 29.7%”是占位数据，不是真实 UniBot 成绩

证据：

- `https://unibot.unitree.com/leaderboard.html` 仍显示「即将发布 / Coming Soon」；`runs.html` 同样 [S2][S4]。
- `leaderboard_data.json` 顶层有 `"generated_from": "gen_leaderboard.py"`；8 个模型 × 32 任务 = 256 条 `task_metrics`；详情视频是占位 [S3]。
- 8 个模型名（MolmoAct2/DexHacker、WALLOSS/Generalist Robotics、DreamZero/World Model Lab、Spirit/VLAGO、DM/Embodied AI Institute、PI/RoboReasoner、GigaBrain/xembody、GR00T/Humanoid Dynamics）是演示条目，不是已确认参赛队 [S3]。

结论：**29.7% 只能当 UI 占位/难度先验，不能当真实头部，也不能用来推断“头部方案”。** 真实榜单发布后，§4 的所有排名假设必须重跑。

### 1.2 步骤分不是并列目标，只是 tie-break

英文/中文参赛手册 [S5][S6] 明确：

- 每个任务 **10 次独立运行**；覆盖 5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰），**每类各 2 次**。
- 单次真机最大 **180 秒**；超时失败。
- 通才赛道必须 **一个模型完成全部 32 个任务**；不允许混合多个模型；架构不限。
- 排名：**32 任务总平均成功率** → 总平均步骤分 → 提交日期早者。

因此：

- 第 7 轮“终局步骤占 39.8% 步骤分”这个算术本身没错，但**它不是“要优化步骤分”的理由**。终局重要的真正原因是：**成功=所有步骤完成，终局是最后一个成功闸门**。
- 不要为 partial score 设计行为；partial score 可能奖励“慢慢做/多做几步”，与成功率冲突。步骤分只在成功率完全相同时才生效，概率很低。
- SSG 仍然有用，但角色改为**内部步骤状态/恢复门控/日志**，不是“为步骤分做规划”。

### 1.3 “地形适应”在 UniBot 里不是腿足地形

UniBot 的 5 类泛化没有上下坡/碎石/楼梯；强行做腿足地形不在评分轴，且没有接口/数据。本轮定义：

| 层 | 内容 | 对应评分轴 | 手段 |
|---|---|---|---|
| 视觉地形 | 桌布颜色/纹理、灯光、背景 | 桌面背景 | 2.5D 增广 + 一致性正则 |
| 几何地形 | 桌面高度/倾斜、相机位姿、容器位置/朝向 | 位置（部分）+ 跨机器人 | 第 4 路立体几何侧车 + 规范桌面系 |
| 语义地形 | 未见物体、同类不同外观、干扰物 | 未见物品 + 干扰物 | 地形卡 + 资产替换 |
| 动态地形 | 人移动物体、撤销步骤、拉上再拉开 | 人为干扰 | 官方备注剧本 + 纠错数据 |

**如果只能做一件事，做“几何地形 + 动态地形”，不要做腿足地形。** 前者直接服务终局放置，后者直接服务 2/10 的人为干扰。

## 2. 规则、数据、统计现实

### 2.1 评测与排名规则（已核实）

| 项 | 规则 | 对策略的含义 |
|---|---|---|
| 任务数 | 32 | 通才单模型，不能按任务切模型 |
| 每任务次数 | 10 | 320 个计分 episode |
| 泛化轴 | 5 类 × 2 次/任务 | 每轴 64 次；单轴噪声大 |
| 单次时限 | 180s | 恢复/重试必须有预算 |
| 排名主键 | 总平均成功率 | 只追成功，不追步骤分 |
| 第二键 | 总平均步骤分 | 仅在成功率完全相同时 |
| 第三键 | 提交日期 | 早提交有微弱优势 |
| 模型 | 单模型完成 32 任务 | 禁 ensemble；可在单 checkpoint 内加辅助头 |
| 部署 | 自部署 + 官方远程 API | 延迟/并发/端口状态要自己负责 |

### 2.3 统计功效：320 次只能看大效应

按 p≈0.3：

```text
SE = sqrt(0.3 × 0.7 / 320) = 2.56pp
95% CI ≈ ±5.0pp
```

两独立比例、双侧 5%、80% power 的近似样本量：

| 真实提升 | 每组所需 | 总所需 | 320 次是否够 |
|---:|---:|---:|---|
| +5pp（0.30→0.35） | ~1374 | ~2748 | 远远不够 |
| +10pp（0.30→0.40） | ~353 | ~706 | 不够 |
| +15pp（0.30→0.45） | ~160 | ~319 | 刚好 |

结论：

- **撤回第 7 轮“+3pp 约 80% 概率排名更高”的说法。** 在官方 320 次里，+3pp 远小于噪声。
- 每任务 10 次，SE≈14.5pp；不要用单任务 10 次归因。
- 每轴 64 次，SE≈5.7pp；单轴结论也要谨慎。
- 离线 A/B 要**配对**（同 episode/同种子/同初始状态）才可能看小效应；官方跑只看大效应。
- 策略：只做大杠杆（终端、抗干扰、场景），不做 2–3pp 的微调；目标 +10–15pp。

## 7. TW-SFT：终端加权 + 结果加权 + 三个辅助头

### 7.1 目标函数

对每个 batch：

```python
# 伪代码；w 为逐帧/逐样本权重
a_pred = wla(obs_3views, lang, proprio)
w = 1.0
w = w + alpha * terminal_mask          # 终端段
w = w + beta  * placement_mask         # 放置/插入/闭合窗口
w = w + gamma * intervention_mask      # 干预/纠错段
w = w + delta * outcome_weight         # 纠错 episode 的成功/恢复结果

L_action = (w * huber(a_pred, a_gt)).sum() / w.sum()
L_place  = huber(placement_head(features), release_pose_gt)
L_prog   = bce(progress_head(features), step_done_gt)
L_int    = bce(intervention_head(features), intervention_gt)

L = L_action + 0.2 * L_place + 0.1 * L_prog + 0.1 * L_int
```

- **终端段**：episode 最后 20–30%，或最后一次夹爪张开前 1–2 秒；放置/插入/闭合任务权重更高。
- **结果加权**：官方数据全成功，`outcome_weight` 主要给纠错数据；失败 autonomous 段降权，干预/恢复段升权。
- **辅助头**：放在 action expert 的 hidden 或 VLM pooled feature 上；小 MLP；同 checkpoint；推理可开关。
- **动作槽掩码**：WLA 54 维含 EE/夹爪/腰/腿/base；桌面任务只对 EE + grippers + waist 计损失，mask legs/base，避免学无关下身动作；推理时 `pivot` 保持当前值。
- **VLM 冻结**：Stage 0–2 冻结；Stage 3 如需 VLM LoRA（rank 8–16），多卡，且监控空间 grounding。

### 7.2 标签从哪来

| 标签 | 来源 | 质量 |
|---|---|---|
| 终端段 | episode 长度 + 夹爪开合事件 + 任务相位 | 高（启发式） |
| 释放位姿 | 最后一次夹爪张开前的 EE pose → 容器系 | 中高（需容器标注） |
| 步骤完成 | 官方 annotation + 物体位姿谓词 + 夹爪事件 | 中（部分任务可自动） |
| 干预段 | 共创 correction episode 的接管标记 | 高（人工标注） |
| 容器系 | STS/标注的容器 6D | 中（透明物需兜底） |

| Stage | 数据 | 训练 | 步数 | 目的 |

## 9. STS/CP：第 4 路相机的桌面几何侧车

### 9.1 为什么是第 4 路

- WLA 只用 `head_stereo_left` + 两腕；`head_stereo_right` 不进 VLA [S14][S15]。
- UniBot API 给 4 路；左右高是已校正立体对 [S9][S11]。
- 右高不增加 VLA 输入，不破坏 3 视图；只做几何，天然合规（经典算法）。

### 9.2 流水线

```python
def terrain_sidecar(obs):
    left  = obs["cam_left_high"]
    right = obs["cam_right_high"]
    depth = stereo_sgbm(left, right, 240, 320)       # 5–10ms
    plane = ransac_plane(depth, min_inlier=0.3)      # 1ms
    T_base_table = calibrate(plane, obs["lower_body"])
    container = detect_container(obs["cam_left_wrist"], depth, T_base_table)
    return T_base_table, container
```

- 桌面平面：RANSAC；法向/高度；inlier <30% 或法向异常 → 标称系兜底。
- 容器 6D：颜色/深度/边缘分割 + OBB/ICP；对称容器 canonicalize yaw；透明/反光用腕部/边缘兜底。
- 规范桌面系：原点在桌面/容器中心，z 向上；EE 动作、OPT 释放位姿、SVL 稳定性都放这个系。
- 频率：2–5Hz + 缓存；不在每个 action chunk 跑全分辨率。
- 延迟：SGBM 5–10ms；平面 1ms；容器 10–30ms；总 <50ms（低分辨率/GPU）。
- 标定：用 `state_d435`/`state_torso` + 官方 URDF 估 head-to-base；头动时用 waist/neck 前向；失败回退。

### 9.3 CP：规范放置

- 从 K 条成功演示取“释放时刻”的 EE pose，变换到容器系；算中位数 + 协方差。
- 目标 `p*` = 中位数；姿态 = 容器接近轴；若分散度大，用任务级先验。
- 放置时：PGL 给 2D 锚点 → 深度反投影 → 容器系 6D；OPT 给 `p*`；SVL 缓放/等待/检查滑移。
- 透明/反光/无纹理：腕部相机 + 容器边缘 + 已知几何；失败则退化为 2D 锚点 + 固定高度。

### 9.4 可证伪

- 桌面平面误差 >2cm 或容器位姿误差 >3cm → 关 STS，回退标称。
- 放置成功率提升 <5pp → 简化 PGL/OPT，只保留 SVL。
- 延迟 p99 >100ms → 降频/降分辨率/缓存。

## 10. RG、SSG、PGL/OPT/SVL、XSM：推理护栏

### 10.1 RG（Recovery Gate）

- 输入：progress head、intervention head、SVL 滑移、动作停滞、步骤 watchdog。
- 状态：continue / slow / retry_step / regrasp / abort。
- 规则：
  - 进度连续 3 个 chunk 不动 → retry_step。
  - 检测滑移/掉落 → nudge/regrasp。
  - 干预头高置信 → slow + 重新观察。
  - 连续失败/接近 180s → abort 到安全。
- 预算：每任务 1–2 次重试；总时长 <150s，留 30s 余量。
- 训练：干预头用共创数据；规则状态机不学习；不做 RL。

### 10.2 SSG（Step State Gate）

- 角色：内部步骤状态、谓词、日志、恢复门控；**不为步骤分做规划**。
- 谓词：夹爪开合、物体抬起、物体入容器、容器闭合、桌面接触。
- 来源：官方 annotation + 物体位姿 + 夹爪事件 + progress head。
- 输出：当前步骤、完成置信、异常；供 RG/PGL/SVL 使用。
- 可证伪：若无门控收益，只保留日志，不占推理预算。

### 10.3 PGL/OPT/SVL

| 模块 | 作用 | 输入 | 输出 | 失败兜底 |
|---|---|---|---|---|
| PGL | 槽位→2D 锚点→6D | 任务槽位、腕/高图、深度 | 容器系 6D | 2D 锚点 + 固定高度 |
| OPT | 最优放置目标 | K 条演示释放位姿 | `p*` + 容差 | 任务级中位数 |
| SVL | 稳定性验证 | 释放后 0.5s 物体位移 | 稳定/滑移 | nudge/regrasp |

- 三者都是推理模块，不是独立模型；不违反单模型。
- SVL 的“慢放→等待→检查”是成功率闸门，不是步骤分优化。

### 10.4 XSM（Cross-episode Success Memory，观察项）

- 存储：任务/指令嵌入、物体/容器规范位姿、相位、成功 action chunk、结果、端口。
- 检索：top-k（k=1–4）余弦/HNSW；置信 = 相似度 × 结果；阈值 0.8。
- 注入：flow 噪声初始化或 action expert 残差；小权重；置信门控。
- 重置：每个 episode 清 buffer；保留任务记忆；**按端口隔离，绝不跨端口共享**。
- 合规：默认 OFF；先问主办方 `reset()` 是否允许跨 episode 任务记忆；若不允许，只用官方数据离线检索（ICR）。
- 证据：Retrieve-then-Steer、RA-VLA、LoopWAM 的部署记忆 [S31][S33][S20]。
- 预期：0–10pp；不是主线；若规则/延迟/公平性任一不过，直接关。

## 11. 工程适配：WLA 54 维 → UniBot EE API

### 11.1 动作映射

- `control_space = "ee"`。
- WLA 54 维含 EE pose（左右各 6）、grippers、waist、base、legs；UniBot API 要 `left/right_ee_pose_gripper_base`（6+6）、grippers（1+1）、`pivot`（7）。
- 直接映射 EE + grippers；`pivot` 保持当前下身/安全值；legs/base 在损失中 mask。
- WLA 原生动作是相对/局部；用官方 adapter 的 compose 逻辑还原到 base 绝对位姿 [S44]。
- 动作 chunk：先 30（1s @30Hz）；若反应慢，测试 15；`obs_delta_indices` 按 API README。
- 状态隔离：每个端口独立 history/reset；共享后端但 per-port state。

### 11.2 观测与图像

- VLA：`head_stereo_left`（336×448）、`wrist_left/right`（336×448）；按官方预处理。
- 几何：`head_stereo_left/right` 低分辨率（240×320）；腕部可选。
- `obs_delta_indices`：高图 1–2 帧，腕图 2–4 帧；不要堆太多，延迟/内存会炸。
- `image_resize`：VLA 336×448；几何 240×320；保持宽高比/居中裁剪。
- 语言：任务指令 + 物体/容器属性；模板化，避免过拟合措辞。

### 11.3 延迟与并发

- 目标：p99 推理 <500ms；chunk 30 给 1s 预算。
- 优化：VLM prefix cache（语言/高图低频）、固定 chunk、批处理多端口、GPU 常驻、避免 Python 热路径。
- 评测记录 latency/action regularity；不要有可变长循环/多次重试在同一 chunk 内。
- 端口：N 个连续端口 8765..；健康检查；每端口状态隔离；共享模型副本/批处理。
- 网络：自部署机器稳定 egress；官方远程调用；准备重连/超时。

## 14. 创新点清单（保留/升级/新增/降级/砍）

### I1. TERRA-CO：用户共创的桌面地形/纠错数据引擎（**押注**）

- **动机**：5 轴里 3 轴（背景/位置/干扰）+ 人为干扰，正好是官方数据覆盖不足、用户能低成本补的地方；LoopWAM/HandITL/DexHiL 证明“部署/纠错数据”比“换更大模型”更有效。
- **差异**：不是问卷/标注，而是“地形卡 + 干预 episode + 覆盖矩阵”的可执行数据协议；非专家可参与；直接对齐评分轴。
- **可行性**：100–200 张卡、300–600 条 episode；5–10 人；2.5D 编辑无需 G1；真机纠错需 1 台 G1 + 操作员。
- **资源**：1 台 G1（可选）、2.5D 编辑/渲染、存储、QA、2–3 周。
- **步骤**：卡 schema → 覆盖矩阵 → 采集 → QA → 训练/验证 → 回流。
- **风险**：外部数据合规；场景不真实；标签噪声；用户差异；默认 OFF + QA + 邮件确认。
- **证伪**：E3 在干扰/恢复轴上 <5pp → 停采，只保留验证用途。

### I2. TW-SFT：终端加权 + 结果加权 + 三个辅助头（**押注**）

- **动机**：成功=所有步骤完成，终局是最后一个闸门；PACER/DexHiL/HandITL 都显示“终端/干预/结果加权”有效。
- **差异**：不改架构，在官方 WLA 上做损失/采样/辅助头；动作槽 mask；单 checkpoint 合规。
- **可行性**：官方代码 + 24GB；标签可由 episode 相位/夹爪事件/容器标注生成；辅助头小。
- **资源**：1×24GB（4090/A6000），10–20k steps，约 1 周；容器标注。
- **步骤**：标签 → 损失 → Stage 0/1 → 调试槽 → 消融。
- **风险**：终端过拟合；标签噪声；VLM 冻结导致欠拟合；LoRA/早停/按轴留出。
- **证伪**：终端步 <5pp → 回退普通 SFT + SVL。

### I3. STS/CP：第 4 路立体几何侧车 + 规范放置（**押注**）

- **动机**：终局放置是成功闸门；第 4 路相机白送；桌面/容器几何是度量问题，不该让 VLM 猜。
- **差异**：经典立体 + RANSAC + 容器 6D + 规范系；不重训、不进 VLA、单模型合规；与 PGL/OPT/SVL 闭环。
- **可行性**：左右高已校正；SGBM 低分辨率 5–10ms；容器标注/演示可生成释放位姿；失败回退标称。
- **资源**：CPU/GPU、标定、容器标注、1 名工程师、2–3 周。
- **步骤**：立体 → 平面 → 容器 6D → 释放位姿 → PGL/OPT/SVL → 调试。
- **风险**：透明/反光；标定漂移；延迟；立体基线未知；腕部/边缘兜底 + 降频 + 标称。
- **证伪**：桌面误差 >2cm 或放置 <5pp → 关 STS/简化。

### I4. RG：恢复门（**保留/升级**）

- **动机**：UniBot 有 2/10 人为干扰；多数模型没有“被撤销后重做”的训练；恢复是成功率的一部分。
- **差异**：progress/intervention 辅助头 + SVL 滑移 + 规则状态机；不做 RL；预算控制。
- **可行性**：干预标签来自纠错数据；规则简单；推理开销小。
- **资源**：纠错数据、小头、1 名工程师、1–2 周。
- **步骤**：训练头 → 阈值 → 状态机 → 调试槽。
- **风险**：误触发；超时；过度重试；置信门控 + 1–2 次上限 + 180s 预算。
- **证伪**：恢复成功率 <5pp 或超时增加 → 关。

### I5. SSG：步骤状态/谓词（**保留/降级**）

- **动机**：内部步骤状态对恢复/放置/日志有用；官方步骤分只是 tie-break。
- **差异**：谓词 + progress head，不做步骤分规划；不单独占模型。
- **可行性**：官方 annotation + 物体位姿 + 夹爪事件；部分任务可自动。
- **资源**：标注、小头、1 名工程师、1 周。
- **步骤**：谓词定义 → 标签 → 训练 → 集成。
- **风险**：标签噪声；谓词歧义；过拟合；只用于门控/日志。
- **证伪**：无门控收益 → 只保留日志。

### I6. PGL/OPT/SVL：放置几何三件套（**保留/升级**）

- **动机**：终局放置需要“槽位→6D→稳定”的闭环；VLA 的 2D 输出不够。
- **差异**：容器系 + K 条演示的释放位姿分布 + 缓放/等待/滑移检查；纯推理。
- **可行性**：STS 提供几何；官方数据有释放事件；腕部可验证；无需训练。
- **资源**：STS、演示、1 名工程师、2 周。
- **步骤**：PGL 锚点 → OPT 目标 → SVL 循环 → 调试。
- **风险**：容器位姿误差；透明物；时间预算；兜底/降级。
- **证伪**：放置 <5pp → 简化。

### I7. XSM：跨 episode 成功记忆（**观察/高风险**）

- **动机**：同任务重复 10 次；成功 chunk 可复用；Retrieve-then-Steer/RA-VLA 有证据。
- **差异**：按任务/端口记忆 + 置信门控 + 规范位姿键；不是模型；可关。
- **可行性**：WLA 特征/动作 chunk 存储；HNSW；延迟低；实现简单。
- **资源**：存储、1 名工程师、1–2 周；无需训练。
- **步骤**：存储 → 检索 → 注入 → 门控 → 评估。
- **风险**：公平性/规则灰区；污染；分布漂移；延迟；默认 OFF + 问主办方 + 端口隔离。
- **证伪**：规则不允许或无增益 → 关。

### I8. DebugLoop：调试槽驱动的部署飞轮（**升级**）

- **动机**：官方 320 次噪声大；调试槽是唯一真机信号；LoopWAM 证明部署 rollout 有效。
- **差异**：提前预约；标准失败分类；每次只改一个变量；回流数据/权重。
- **可行性**：官方不计分单任务通道；5–10 次/任务；远程。
- **资源**：调试槽、日志、1 名工程师、全程。
- **步骤**：预约 → 跑 → 标注 → 回流 → 再跑。
- **风险**：槽位稀缺；过拟合调试任务；延迟；按轴留出 + 多任务验证。
- **证伪**：调试收益不迁移 → 换任务/停。

### I9. WLA 适配 + 延迟工程（**工程保留**）

- **动机**：54 维→UniBot EE/pivot；30Hz；多端口；评测记录延迟/规律性。
- **差异**：EE 模式 + 动作槽 mask + pivot hold + prefix cache + 批处理 + per-port state。
- **可行性**：官方 adapter；API README；24GB；benchmark。
- **资源**：1 名工程师、GPU、网络、1–2 周。
- **步骤**：adapter → 回放 → 延迟 → 并发 → 压测。
- **风险**：动作映射错；延迟尖峰；端口串状态；安全；回放/压测/隔离。
- **证伪**：p99 >500ms 或回放误差大 → 优化/降 chunk/换部署。

### I10. Terrain Consistency Regularization（**合并到 I2**）

- **动机**：2.5D 增广改变外观但不应改变动作语义；一致性正则可防“记背景”。
- **差异**：干净/增广成对样本，action expert 输出一致性损失；小权重。
- **可行性**：增广管线生成成对图；训练时加 loss；无需新模型。
- **资源**：增广、算力、1 名工程师、1 周。
- **步骤**：成对生成 → loss → 消融。
- **风险**：过正则；增广不真实；标签噪声；权重 0.05–0.1 + 人工检查。
- **证伪**：背景/位置轴无增益 → 去掉。
