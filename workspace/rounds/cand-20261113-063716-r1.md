# 第 3 轮迭代（灵感循环 v3：「遥操作」×「预训练」）—— 从「仿真造干扰」转向「示教里挖干预」：TAP 栈

> 承接第 2 轮 v2（UIP-01′~15）。v2 的最大风险是「用仿真过拟合仿真」：它把恢复能力的全部赌注押在 UIP-12（Gazebo 脚本化反向撤回）上。本轮两个灵感词给出一条**更便宜、更在分布内**的替代路径：公开的 32 个示教数据集不只是 `(o,a)` 监督对，它们还是**人类操作者的干预日志**——包含停顿、回退、重抓、重对齐、重试。规则里的 `human_*` 是「外部人手把进度撤回」；示教里的纠错是「操作者自己把进度撤回再恢复」。两者的动作语义都是 `undo → recover`，差别只在**谁施加、何时施加、施加在物体还是机器人**。预训练则让我们不必从零学：先在示教上做**可逆性 / 进度 / 时序**的自监督预训练，得到一个不依赖 Gazebo 的 verifier；再把 32 任务压进一条通才骨干，用干预感知的数据混合与技能头适配。v3 的口号是：**先学会看懂回退，再学会自己做回退。**

## 0. 先修正一个接口事实（比新想法更重要）

v2 的 UIP-13 假设「metadata 声明全局最大 k，实际每次可返回 ≤k 步」。重读 README §3：`action_chunk_size` 是「每次返回的动作步数」，每个动作数组形状为 `(T_a, …)`，索引 0 先执行。**这是精确长度，不是上界**；评测端按 `T_a` 校验，返回更短的块大概率被拒。因此：

- **k 是提交级全局常量**，不能按任务阶段 / episode 动态切；
- 真正的「适应性」只能放在**块内内容的模式调度**（前几步纠错、后几步名义）与**下一次调用的模式切换**；
- v2 的 ACS 需从「动态块长」改写为「全局块长选择 + 块内模式调度」。

这个修正把「实时性」从工程问题变成了一个可推导的优化问题：给定遥操作估计的人类纠错反应时，选择唯一的 k。

## 1. 两个灵感词的直觉解释

### 1.1 遥操作：示教不是「答案」，是「人类如何改答案」的过程记录

直觉：我们过去把示教数据当成 `observation → action` 的监督对，只学「怎么做对」。但遥操作数据里真正稀缺的信息是「做错 / 被打断之后怎么回来」：操作者会在抓滑后回退重抓、在插入失败后拔出重对准、在拉链卡住后反向松一下再拉。**这些片段在数据里是自然出现的，不需要我们去仿真里脚本化制造。** 它们与 `human_*` 的强制撤回共享同一个底层结构：先把已完成进度 undo 掉，再由操作者恢复；差别只在施加者与时序。

直觉 2：遥操作还携带**人类时序先验**。人看到误差到开始纠正有一个反应时（约 200–400 ms），完成一次回退有一个持续时间。评测中的人为干扰也由人施加，其时序统计与遥操作纠错并非同分布，但可作为**先验**；结合 chunk 长度，可以推导「开环执行期间被撤回的期望进度损失」，从而选 k。

### 1.2 预训练：不是「外挂大模型」，而是「把示教里可自监督的结构先学出来」

直觉：32 任务、约 3.2 万条示教、30 fps、四路相机，足以做**领域内自监督预训练**，而不必依赖外部权重（也规避「单模型 / 外部模型」合规争议）。可自监督的结构有四类：

1. **时序方向**：正放 vs 倒放（可逆性 / 物理方向）；
2. **进度单调性**：成功示教的进度应非降；回退片段应出现局部下降；
3. **逆动力学**：相邻帧之间发生了什么动作；
4. **语言-片段对齐**：任务语言与视频片段 / 子目标边界对齐。

这些目标不需要人工标注，且直接产出我们最缺的东西：**一个能在测试时判断「进度是否被撤回」的 verifier**。外部预训练 VLA 权重是另一条可选路径，但必须在手册确认允许后再启用；默认方案是完全领域内的。

## 2. 核心洞察：三个可检验的桥接假设

- **H5（回退迁移假设 RTA）**：示教中的「自愿回退」与评测中的「强制撤回」在**状态-动作语义**上共享一个 `undo` 核，差异主要是施加者、时机与幅度。若成立，则用示教回退预训练的检测器可迁移到外部干扰；若不成立，退回到 v2 的 Gazebo DRF。
- **H6（进度单调性可学）**：存在一个可从示教中学出的标量进度函数 `P(o)`，使成功轨迹上 `P` 近似非降、回退片段上出现显著负跳。它可作为 UIP-01′ 的 `regressed` 判据，替代手工几何谓词。
- **H7（块长-反应时最优）**：给定人类纠错的反应时分布与单次推理延迟，存在唯一的全局 `k*` 最小化「开环期间被撤回的期望进度损失 + 推理 / 可信度成本」；接触密集任务可用安全上限截断。

## 3. 严谨定义（v3 增量）

**定义 50（示教轨迹与进度泛函）**
设第 i 条示教轨迹为 \(\tau_i=\{(o_{i,t},a_{i,t})\}_{t=1}^{T_i}\)，任务语言为 \(l_i\)。进度泛函 \(P_\theta:\mathcal O\times\mathcal L\to[0,1]\) 满足：对成功示教中大多数 \(t\) 与 \(\Delta>0\)，
\[
\mathbb E\big[\mathbf 1(P_\theta(o_{t+\Delta},l)<P_\theta(o_t,l)-\epsilon_p)\big]\le \eta .
\]
子目标谓词 \(g_j(o)\in\{0,1\}\) 与任务的计分点对齐；\(P\) 与 \(g_j\) 共同构成「进度坐标」。

**定义 51（自然回退事件与恢复三元组）**
若 \((t_1,t_2,t_3)\) 满足 \(t_1<t_2<t_3\)、\(P(o_{t_2})<P(o_{t_1})-\delta\)，且至少满足一项：
\[
g_j(o_{t_2})<g_j(o_{t_1})\quad\text{或}\quad \mathrm{backtrack}(o_{t_1:t_2})>L_{\min},
\]
并且 \(P(o_{t_3})\ge P(o_{t_1})\)，则称其为一次自然回退事件，三元组为 \((o_{t_1},o_{t_2},o_{t_2:t_3})\)，分别对应「回退前 / 回退谷底 / 恢复段」。任务 i 的自然干预密度定义为 \(\mu_i=\mathbb E[|E_i|/T_i]\)。

**定义 52（可逆性对比预训练目标 RCP）**
对片段 \(c=o_{t:t+H}\)，记正放为 \(c^+\)、倒放为 \(c^-\)。令 \(f_\theta\) 为共享编码器，\(h_\psi\) 为方向判别头，\(P_\phi\) 为进度头，\(\mathrm{ID}\) 为逆动力学头。预训练损失为
\[
\mathcal L_{\mathrm{RCP}}=\mathcal L_{\mathrm{rev}}+\lambda_m\mathcal L_{\mathrm{mono}}+\lambda_i\mathcal L_{\mathrm{inv}}+\lambda_a\mathcal L_{\mathrm{act}}+\lambda_l\mathcal L_{\mathrm{lang}},
\]
其中
\[
\mathcal L_{\mathrm{rev}}=\mathrm{BCE}(h_\psi(f_\theta(c^+)),0)+\mathrm{BCE}(h_\psi(f_\theta(c^-)),1),
\]
\[
\mathcal L_{\mathrm{mono}}=\mathbb E_{c^+}\mathrm{ReLU}\big(-(P_\phi(c^+_{\text{end}})-P_\phi(c^+_{\text{start}}))\big)
+\mathbb E_{c^-}\mathrm{ReLU}\big(P_\phi(c^-_{\text{end}})-P_\phi(c^-_{\text{start}})\big).
\]
注意：倒放片段**只用于方向 / 序关系头**，不用于动作模仿；动作头只在正放示教上训练。这样可避免把违反物理的倒放动作当成监督。

**定义 53（干预感知数据混合与有效样本量）**
对片段 c 赋予权重
\[
w_c=(1+\beta\mathbf 1[c\in\mathcal I])(1+\gamma\mathbf 1[c\in\mathcal U]),\qquad q(c)\propto w_c\,p(c),
\]
其中 \(\mathcal I\) 为含回退 / 纠错的片段，\(\mathcal U\) 为含未见物品变体的片段。有效样本量按
\[
n_{\mathrm{eff}}=\frac{(\sum_c w_c)^2}{\sum_c w_c^2}
\]
报告，并按 episode 分块采样，避免相邻帧泄漏。所有「过采样回退」的实验必须匹配 \(n_{\mathrm{eff}}\)，否则提升可能只是样本量假象。

**定义 54（反应时风险与全局块长）**
令帧间隔 \(\Delta=1/30\) s，块时长 \(T=k\Delta\)。设外部撤回的风险率为 \(\lambda_{\mathrm{ext}}(u)\)，单位时间进度损失率为 \(L_{\mathrm{prog}}\)，单次推理成本为 \(c_{\mathrm{infer}}\)，可信度成本为 \(c_{\mathrm{cred}}(T)\)。开环执行一个块的期望损失为
\[
J(k)=L_{\mathrm{prog}}\int_0^{T}(T-u)\lambda_{\mathrm{ext}}(u)\,du+\frac{c_{\mathrm{infer}}}{T}+c_{\mathrm{cred}}(T).
\]
常数风险率下有闭式解
\[
J(k)=\frac12 L_{\mathrm{prog}}\lambda_{\mathrm{ext}}T^2+\frac{c_{\mathrm{infer}}}{T}+c_{\mathrm{cred}}(T),\qquad
k^*=\left\lfloor \frac{1}{\Delta}\left(\frac{c_{\mathrm{infer}}}{L_{\mathrm{prog}}\lambda_{\mathrm{ext}}}\right)^{1/3}\right\rfloor .
\]
由于 k 是全局常量，实际选择为 \(k^*=\arg\min_k\sum_j w_jJ_j(k)\)，并受接触密集任务的 \(k_{\max}\) 截断。直觉：干扰越频繁、进度越宝贵、推理越便宜，块应越短；反之块可变长。

**定义 55（RTA 的总变差界）**
设 \(P_s^{\mathrm{op}}\) 与 \(P_s^{\mathrm{ext}}\) 分别为状态 s 下「自愿回退」与「强制撤回」的下一状态分布。若存在耦合使
\[
d_{\mathrm{TV}}(P_s^{\mathrm{op}},P_s^{\mathrm{ext}})\le \epsilon(s),\qquad \sup_s\epsilon(s)\le \epsilon_{\max},
\]
则对任何损失关于状态分布总变差为 \(L\)-Lipschitz 的回退检测器，有
\[
R_{\mathrm{ext}}\le R_{\mathrm{op}}+2L\epsilon_{\max}+O\!\left(\sqrt{\frac{\log(1/\delta)}{n_{\mathrm{eff}}}}\right).
\]
这是**条件性结论**：RTA 本身是假设，不是定理。E202 用 Gazebo 的强制撤回作为 ext 的代理来估计 \(\epsilon_{\max}\)，再用真机校准；若界太松，则不把示教回退当作外部干扰的替代。

## 4. 从 v2 到 v3 的清单手术

- **旗舰转移**：v2 的旗舰是 UIP-01′ + 09′ + 12（Gazebo 造干扰）；v3 改为 **UIP-17 RCP（可逆性预训练）× UIP-16 TRI（示教回退挖掘）× UIP-01′**。恢复能力的**数据主源**从仿真脚本改为示教自然回退。
- **降级**：UIP-12 DRF 从「主数据工厂」降为「物理增强 + RTA 审计探针」；UIP-11 GSO 从「训练环境」降为「离线结构裁判」。
- **升级**：UIP-09′ 由 UIP-16/17 驱动；UIP-01′ 的 verifier 由手工几何规则升级为「几何 + 学习式进度 / 回退头」的混合判据。
- **改写**：UIP-13 ACS → **GCS（Global Chunk Selection）+ 块内模式调度**；k 只选一次，适应性放进块内容。
- **合并**：UIP-14 MSGR 并入 **UIP-18 GAP（通才动作预训练）**，技能图变成通才骨干上的技能头 / 适配器。
- **新增**：UIP-16 TRI、UIP-17 RCP、UIP-18 GAP、UIP-19 RTP。保留 UIP-02′、05、08′、15；继续封存 04、10。

## 5. 四个新机制的一句话

- **UIP-16 TRI**：从示教里挖 `(pre, undo, recover)` 三元组，构造恢复数据，不靠脚本。
- **UIP-17 RCP**：正放 / 倒放对比 + 进度单调 + 逆动力学，预训练出「回退检测器 / 进度头」。
- **UIP-18 GAP**：一条通才骨干吃 32 任务示教，干预片段过采样，技能头轻量适配。
- **UIP-19 RTP**：用遥操作反应时先验推导全局 k*，把实时性变成可计算的选择。

## 6. 本轮最大风险

**一句话**：如果公开示教里的自然回退片段密度极低，或「自愿回退」与「强制撤回」的视觉 / 动力学差异超出 RTA 的总变差界，那么 TRI / RCP 会退化成「在干净示教上过拟合」，此时必须无痛回退到 v2 的 Gazebo DRF，而不是硬把示教回退说成外部干扰。

**→ 本轮最值得押注：UIP-17 RCP × UIP-16 TRI × UIP-01′ 的「示教回退预训练-检测-重做」闭环**，先用 E201 / E202 做可行性闸门；通过后再用 UIP-18 GAP 放大通才能力、用 UIP-19 RTP 选全局 k。

## 1. 旗舰深潜：UIP-17 RCP（Reversal-Centric Pretraining）

### 1.1 机制

用 32 个公开示教数据集做**领域内自监督 + 多任务预训练**，让共享编码器同时学会四件事：

1. **时序方向**：给正放片段与倒放片段二分类，学到「物理过程往哪个方向走」；
2. **进度单调性**：成功示教上进度非降，回退片段上出现负跳；
3. **逆动力学**：从相邻帧推断动作，逼编码器保留「什么动作导致什么状态变化」；
4. **语言-片段对齐**：任务语言与子目标边界 / 片段表示对齐，服务未见物品的语义泛化。

产出三个可复用头：

- \(P_\phi(o,l)\)：进度头，输出 0–1 的完成度；
- \(R_\psi(o_{t-W:t},l)\)：回退头，输出「最近 W 帧是否在撤回进度」的概率；
- \(f_\theta(o,l)\)：共享视觉-语言表示，供动作头、技能头、UIP-01′ verifier 共用。

### 1.2 为什么这比 Gazebo 造干扰更划算

| 维度 | UIP-12 Gazebo 脚本造干扰 | UIP-17 示教回退预训练 |
|---|---|---|
| 数据来源 | 脚本化机械手 / 人工在仿真里施加 | 公开示教里已有的操作者纠错 |
| 分布 | 仿真视觉 / 接触，存在 sim-to-real gap | 真实相机、真实接触、真实操作者 |
| 标注 | 需要为每个任务写干扰脚本与判据 | 进度 / 时序 / 逆动力学均可自监督 |
| 成本 | 建 32 个场景 + 调物理 | 一次预训练，多任务复用 |
| 主要风险 | 仿真过拟合（v2 已指出） | 自愿回退 ≠ 强制撤回（RTA 假设） |

RCP 不否认 Gazebo 的价值，但把它从「数据主源」改成「审计探针」：用 Gazebo 的强制撤回测试 RCP 检测器是否真的能迁移（E202）。这比「在 Gazebo 里训练、在 Gazebo 里刷分」更不容易自我欺骗。

### 1.3 训练目标（完整版）

\[
\mathcal L_{\mathrm{RCP}}
=\mathcal L_{\mathrm{act}}
+\lambda_i\mathcal L_{\mathrm{inv}}
+\lambda_r\mathcal L_{\mathrm{rev}}
+\lambda_m\mathcal L_{\mathrm{mono}}
+\lambda_l\mathcal L_{\mathrm{lang}}.
\]

- \(\mathcal L_{\mathrm{act}}\)：动作块监督（L1 / flow matching，只用在正放示教）；
- \(\mathcal L_{\mathrm{inv}}=\lVert a_t-\mathrm{ID}(f(o_t),f(o_{t+1}))\rVert^2\)；
- \(\mathcal L_{\mathrm{rev}}=\mathrm{BCE}(R_\psi(c^+),0)+\mathrm{BCE}(R_\psi(c^-),1)\)；
- \(\mathcal L_{\mathrm{mono}}\) 见想法区定义 52；
- \(\mathcal L_{\mathrm{lang}}\)：语言-片段对比学习（可用 InfoNCE）。

**关键防作弊**：倒放片段只进方向头 / 进度头，不进动作头。否则模型会学到「倒放的动作也是合法动作」，在真机上产生危险的反向运动。

### 1.4 失败模式

- 如果示教里根本没有自然回退，\(\mathcal L_{\mathrm{mono}}\) 只剩「正放单调」这一侧，RCP 会退化为普通进度回归；
- 如果倒放片段靠「液体倒流 / 重力异常」就能被轻易分类，方向头可能学到捷径特征，迁移到外部干扰时失效；
- 如果外部干扰的视觉形态与示教纠错差异过大，RTA 的总变差界会很松，检测器不可靠。

因此 RCP 必须与 E201/E202 闸门绑定，不能默认成功。

## 2. UIP-16 TRI（Teleop Reversal Imputation / 示教回退挖掘）

### 2.1 挖掘流水线

1. **进度头预训练**：先用 UIP-17 的 \(P_\phi\) 给每条示教打进度曲线；
2. **子目标分段**：对 \(P_\phi\) 做变点检测，结合夹爪开合事件与计分点谓词，切出子目标；
3. **回退事件检测**：按定义 51 找 \(P\) 的显著负跳 + 子目标谓词回退 / 末端轨迹反向；
4. **恢复确认**：要求 \(P\) 在后续窗口回到事件前水平，排除「失败后重开 episode」；
5. **模式标注**：把片段标为 `NOM`（名义）、`COR`（小纠错）、`REC`（回退后恢复）；
6. **三元组构造**：输出 \((o_{t_1}, o_{t_2}, o_{t_2:t_3})\)，并附语言、任务、计分步索引；
7. **质量闸门**：每任务抽 100 段人工审计；若某任务自然回退事件 < 5，标记为「稀疏」，不进入 TRI 主训练集。

### 2.2 伪代码

```python
def mine_reversals(traj, P, subgoals, delta=0.08, Lmin=0.02, W=15):
    events = []
    T = len(traj)
    for t1 in range(T - 1):
        # 只看局部窗口，避免 O(T^2) 在长 episode 上爆炸
        for t2 in range(t1 + 1, min(T, t1 + 3 * W)):
            if P(traj[t2]) >= P(traj[t1]) - delta:
                continue
            pred_regressed = any(
                subgoals[j](traj[t2]) < subgoals[j](traj[t1])
                for j in range(len(subgoals))
            )
            if not pred_regressed and backtrack_len(traj, t1, t2) <= Lmin:
                continue
            t3 = next(
                (s for s in range(t2, min(T, t2 + 4 * W))
                 if P(traj[s]) >= P(traj[t1])),
                None,
            )
            if t3 is not None:
                events.append((t1, t2, t3))
            break
    return events


def build_triples(dataset, P, subgoals):
    triples, sparse_tasks = [], []
    for task, episodes in dataset.items():
        n_events = 0
        for traj in episodes:
            ev = mine_reversals(traj, P, subgoals[task])
            n_events += len(ev)
            for t1, t2, t3 in ev:
                triples.append({
                    "pre": traj[t1],
                    "undo": traj[t2],
                    "recover": traj[t2:t3 + 1],
                    "task": task,
                    "mode": "REC",
                })
        if n_events < 5:
            sparse_tasks.append(task)
    return triples, sparse_tasks
```

### 2.3 数据产品

- **恢复三元组**：训练「检测到回退 → 切 REC 模式 → 重做子目标」；
- **模式标签**：给 UIP-18 的动作头提供 `NOM/COR/REC` 条件；
- **进度弱标注**：给 UIP-01′ verifier 提供每任务的进度曲线先验；
- **失败案例库**：被质量闸门拒绝的片段可用于训练「不要把这些误判为回退」的负例。

### 2.4 稀疏时的降级路径

若 E201 显示自然回退太稀疏：

1. 先用 UIP-17 的倒放 / 时序目标继续预训练 verifier（这部分不依赖自然回退）；
2. 恢复策略退回 UIP-12 DRF 的 Gazebo 脚本数据；
3. 把 TRI 降为「辅助微调」，只在少数回退密集任务上使用；
4. 不把「示教回退」包装成「外部干扰」对外宣称，避免过度承诺。

## 3. UIP-18 GAP（Generalist Action Pretraining / 通才动作预训练）

### 3.1 架构

```text
                    ┌── P_φ  (progress head)      → UIP-01′ verifier
obs history ──> f_θ ─┼── R_ψ  (reversal head)      → UIP-01′ regressed 判据
   + language       └── π_ω  (action-chunk head)  → 精确 k 步动作块
                         └── skill adapters (抓/放/插/倒/拉链/折叠/堆叠/分拣/开合/挑取)
```

- **单骨干**：视觉-语言编码器 + 动作块 Transformer；
- **技能头 / 适配器**：把 v2 的 UIP-14 技能图落到同一骨干上，满足「单模型多任务」合规；
- **模式条件**：动作头接受 `mode ∈ {NOM, COR, REC}`，与 UIP-16 的标注对齐；
- **精确 k**：动作头每次输出严格 `(k, …)`，不再声称可返回变长块。

### 3.2 训练配方

| 项目 | 设置 |
|---|---|
| 数据 | 32 任务公开示教（约 3.2 万 episodes，30 fps，四路相机） |
| 采样 | 预训练 5 fps 抽帧；动作头用原始 30 fps 片段 |
| 分辨率 | 224×224（预训练）/ 训练后按 `image_resize` 选择 |
| 输入 | 头部双目 + 双腕（4 路）；语言指令；关节 / EE 状态 |
| 目标 | \(\mathcal L_{\mathrm{act}}+\lambda_i\mathcal L_{\mathrm{inv}}+\lambda_r\mathcal L_{\mathrm{rev}}+\lambda_m\mathcal L_{\mathrm{mono}}+\lambda_l\mathcal L_{\mathrm{lang}}\) |
| 混合 | 干预片段过采样（\(\beta\)），未见物品变体过采样（\(\gamma\)），按 episode 分块 |
| 规模 | 小配置：冻结视觉骨干 + 10M 参数头，单卡可跑；大配置：端到端 ViT-B，1–8 卡数天 |
| 服务 | 单骨干共享 + 每端口状态 / KV 隔离 + 跨端口批处理（UIP-08′） |

### 3.3 与 v2 UIP-14 的关系

v2 的 MSGR 是「技能图路由 + 参数高效技能头」；GAP 把「路由」升级为「预训练表示 + 模式条件 + 技能适配器」：

- 路由不再只靠语言，还靠进度 / 回退头的状态；
- 技能头共享通才表示，冷启动更好；
- 干预片段让技能头见过「做错后怎么回来」，而不是只见过成功轨迹。

### 3.4 资源与合规

- **默认领域内预训练**：不依赖外部权重，避免「单模型 / 外部模型」争议；
- **外部 VLA 初始化**：仅在手册确认允许后启用；若启用，仍只保留一条推理骨干；
- **显存**：若 N 端口共享一个大模型，必须做请求批处理与每端口状态隔离；否则 N 份拷贝会拖垮显存与延迟；
- **可信度**：批处理会引入排队抖动，需用 UIP-15 的延迟预算与 UIP-08′ 的隔离策略压平。

## 4. UIP-19 RTP（Reaction-Time Prior / 反应时先验与全局 k*）

### 4.1 从遥操作估计人类纠错时序

对每个自然回退事件，定义：

- **反应时** \(\ell_{\mathrm{react}}=t_{\mathrm{action\ onset}}-t_{\mathrm{error\ onset}}\)；
- **回退时长** \(\ell_{\mathrm{undo}}=t_{\mathrm{valley}}-t_{\mathrm{action\ onset}}\)；
- **恢复时长** \(\ell_{\mathrm{rec}}=t_{\mathrm{recover}}-t_{\mathrm{valley}}\)。

对 \(\ell_{\mathrm{react}}\) 拟合一个生存 / 风险模型（Weibull 或对数正态），得到 \(\lambda_{\mathrm{op}}(\ell)\)。评测中的外部干扰由人施加，其风险率 \(\lambda_{\mathrm{ext}}\) 与 \(\lambda_{\mathrm{op}}\) 不同，但可用作先验；用 Gazebo DRF 与真机校准缩放因子 \(\kappa\)：\(\lambda_{\mathrm{ext}}\approx\kappa\lambda_{\mathrm{op}}\)。

### 4.2 选择全局 k*

按想法区定义 54：

\[
J(k)=\frac12 L_{\mathrm{prog}}\lambda_{\mathrm{ext}}(k\Delta)^2+\frac{c_{\mathrm{infer}}}{k\Delta}+c_{\mathrm{cred}}(k),
\qquad
k^*=\arg\min_k\sum_j w_jJ_j(k).
\]

由于 k 是全局常量，且接触密集任务有安全上限 \(k_{\max}\)，实际取

\[
k^*=\min\left(\arg\min_k\sum_j w_jJ_j(k),\;k_{\max}\right).
\]

**读法**：

- 干扰越频繁（\(\lambda_{\mathrm{ext}}\) 大）→ 块越短；
- 单次推理越贵（\(c_{\mathrm{infer}}\) 大）→ 块越长；
- 进度越宝贵（\(L_{\mathrm{prog}}\) 大）→ 块越短；
- 接触密集任务（插网线、合盖、拉链）→ 用 \(k_{\max}\) 截断，不让公式把块拉长。

### 4.3 块内模式调度

k 固定后，真正的适应性放在块内容：

- `NOM` 块：前 \(m\) 步带「守卫」小修正，后 \(k-m\) 步名义动作；
- `REC` 块：整块用恢复模式，直到进度回到事件前水平；
- `COR` 块：小幅纠错，不触发完整重做。

这样既遵守 `(k, …)` 的精确形状，又保留「检测到回退后立刻改变下一块行为」的反应性。

## 5. 更新后的旗舰算法（UIP-01′ + 16 + 17 + 19）

```python
class TAPPolicy:
    """Teleop-Anchored Pretraining policy.

    关键约束：k 是提交级全局常量，get_action 每次必须返回精确 (k, ...)。
    """

    def __init__(self, trunk, progress_head, reversal_head, k,
                 delta=0.08, r_thr=0.7, W=15):
        self.trunk = trunk
        self.P = progress_head
        self.R = reversal_head
        self.k = k                 # 由 UIP-19 的 RTP 选定，全局唯一
        self.delta = delta
        self.r_thr = r_thr
        self.W = W

    def reset(self):
        self.Pmax = 0.0
        self.mode = "NOM"
        self.hist = []

    def get_action(self, obs):
        self.hist.append(obs)
        self.hist = self.hist[-self.W:]

        p = self.P(obs, obs["observation.language"])
        r = self.R(self.hist, obs["observation.language"])

        # 回退判据：进度负跳 或 回退头高置信
        if p < self.Pmax - self.delta or r > self.r_thr:
            self.mode = "REC"
        else:
            if p > self.Pmax:
                self.Pmax = p
            if self.mode == "REC" and p >= self.Pmax - self.delta / 2:
                self.mode = "NOM"

        action = self.trunk(obs, mode=self.mode, T=self.k)
        assert action["action.left_arm"].shape[0] == self.k
        return action
```

**与 v2 的差异**：

- v2 的 verifier 是手工几何谓词；v3 是「学习式进度 / 回退头 + 几何谓词兜底」；
- v2 的 k 可在阶段间变化；v3 的 k 全局固定，适应性放进 `mode`；
- v2 的恢复数据来自 Gazebo；v3 的主源是示教回退，Gazebo 只做审计。

## 8. Kill criteria 与负结果处理

- **E201 失败** → 自然回退太稀疏：TRI 不作为主数据源；UIP-17 仍可用倒放 / 时序目标训练 verifier，恢复策略退回 UIP-12 DRF。
- **E202 失败** → RTA 不成立：不把示教回退当作外部干扰的替代；RCP 只做「领域内进度 / 方向」头，外部撤回检测改用 Gazebo / 真机数据。
- **E203 失败** → 预训练没有超过随机初始化：放弃大规模预训练，改用轻量进度头 + 手工几何判据，节省算力。
- **E204 失败** → TRI 数据不如 DRF：保留 DRF 为主，TRI 仅作辅助；不为了「故事好听」硬推示教回退。
- **E207 失败** → \(k^*\) 对风险率估计敏感：改用保守固定 k（如 8 或 16）+ 块内守卫，不追求公式最优。
- **E209 合规不明** → 默认不用外部权重；所有实验以领域内预训练为基线。

## 9. 合规、可信度与风险

- **单模型合规**：所有头 / 适配器共享一条推理骨干；外部 VLM 验证器不再作为默认方案（v2 已警示）；若用外部预训练权重，先确认手册是否允许。
- **遥操作事实待核实**：HF 数据卡只写 LeRobot 与 AV1 视频，未明写「遥操作」；本轮把「示教包含人类纠错 / 回退」作为可检验假设，不当作已证实事实。若数据实际是纯成功、无纠错，E201 会直接暴露。
- **数据许可**：数据卡标注 Apache-2.0；仍需逐个数据集确认，尤其是再分发与商用条款。
- **仿真过拟合**：Gazebo 只做审计与增强，不用来宣称真机性能；RTA 必须用真机锚点校准。
- **延迟与端口**：预训练模型越大，N 端口并发越危险；单骨干 + 批处理 + 每端口状态隔离是硬要求，且批处理本身会引入排队抖动，需要 UIP-15 的延迟预算兜底。
- **动作统计规律性**：倒放片段绝不能进动作头；否则可能产生反向 / 异常动作，触发可信度审查。
- **未见物品**：GAP 的语言条件化有帮助，但不能保证；UIP-05 的语义可供性仍是必要的兜底。

## 11. 本轮最大风险 & 押注
