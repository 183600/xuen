# 第 8 轮 · SCOPE：把目标检测变成"数据引擎 + 步骤裁判"

> 检索/复核日期：2026-10-27（UTC）。按状态文件轮次续编；本轮也是灵感循环第 2 轮。赛事身份不变：宇树科技 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「目标检测」「数据规模」「机器人竞赛」。我先去核实规则与榜单，结果发现上一轮有一个关键误读——排名不是"成功率与步骤分综合"，而是**成功率优先、步骤分只破同分**；每个任务 10 次 = 5 类泛化 × 2 次。这个修正把本轮的主判断从"攻终局步骤分"改成"攻成功率闸门 + 用步骤分做训练信号"。然后我把三个词合成一句话：**榜首不到 30% 不是模型不够大，而是缺少一个能在五类泛化下持续工作的对象/部件级状态；目标检测是把这个状态做出来的最便宜接口，也是把 32k 演示变成千万级监督的数据引擎；机器人竞赛的成功率优先与高方差，则决定了我们应该追求大而稳的增益，而不是在榜单噪声里抠小数点。**

---

## 0. 本轮先核实：八个会改变判断的事实

### 0.1 排名规则修正：成功率优先，步骤分只破同分

我抓了中英文参赛手册（[S2][S3]）。关键原文：

- 每个任务执行 **10 次独立运行**，5 类泛化（位置、干扰物、背景、未见物品、人为干扰）**各 2 次**；单次最长 **180 秒**。
- 实时榜单按 32 个任务的**总平均成功率**排序；成功率相同才看**总平均步骤分**；再相同看**提交日期**，早者靠前。
- 只允许**一个模型**完成全部 32 任务；不得按任务混合多个模型；World Model / VLA 都可。
- 单任务测试通道不计分，只用于调试。

这修正了上一轮"成功率与步骤分综合排序"的表述。**成功率是唯一主目标；步骤分是破同分和训练信号。** 上一轮的"终局放置是闸门"仍然成立，因为终局步决定成功；但"步骤分大头"不应该成为优化目标本身。这个修正很关键：它意味着一个 30% 成功 / 39 步骤分的模型，排名高于 29% 成功 / 45 步骤分的模型。

### 0.2 榜单仍是脚本生成的演示数据，不是真实评测

`leaderboard_data.json` 仍写着 `"generated_from": "gen_leaderboard.py"`，发布时间 2026-10-08；8 个模型 × 32 任务 = 256 条；详情页明确写"测试视频占位，后续可替换为真实视频文件"（[S5][S6][S7]）。所以：

- 29.7% / 39.0 的榜首数字只能当**结构先验**，不能当真实排名。
- 8 个模型的名字对应真实模型家族（MolmoAct2、Wall-OSS-0.5、DreamZero、Spirit-v1.5、DM0、π0.5、GigaBrain-0、GR00T N1.5），可以借它们的公开论文分析"头部做法"，但不能说它们在 UniBot 上真的跑了这个分数。
- 榜单的结构（成功率 20.5–29.7%，步骤分 28.1–39.0，步骤分普遍高 6–12pp）与"失败集中在后段步骤"一致，可作为弱先验。

### 0.3 头部八个模型家族：没有唯一赢家，只有不同的归纳偏置

我逐个查了公开资料（[S11]–[S26]）：

- **MolmoAct2**：Molmo2-ER 空间/具身推理 backbone + 深度 token + 2D 轨迹 + flow-matching action expert；3.3M 具身推理样本、720h 双臂数据。强在显式空间 grounding。
- **Wall-OSS-0.5**：4B VLA（3B VLM + action expert），20+ 本体、每 epoch 100 万条轨迹，deployment-oriented pretraining。强在广谱本体先验。
- **DreamZero**：14B 视频扩散 World Action Model，联合预测未来视频与动作，7Hz 闭环，声称新任务/新环境 2× 泛化。强在物理动力学。
- **Spirit-v1.5**：Qwen3-VL-4B + DiT action head，真实数据、强调 diversity；RoboChallenge Table30 50.33% 第一。强在真实机器人基准。
- **DM0**：embodied-native VLA，Qwen3-1.7B + flow matching，1.2T tokens（web + 驾驶 + 机器人）。强在物理先验广。
- **π0.5**：π0 + 异构 co-training，训练里显式使用 object detections、subtask prediction、web data。强在开放世界语义。
- **GigaBrain-0**：world-model 生成数据（视频/real2real/view/sim2real）+ RGBD + embodied CoT；后续 0.5/0.7 做到 10k+ 小时。强在数据引擎。
- **GR00T N1.5**：Eagle-2 VLM + DiT 双系统，data pyramid；公开实现中 VLM 常被冻结。强在语言跟随与 humanoid 先验。

如果榜单结构为真，头部不是"参数越大越强"，而是"空间/物理先验越显式越靠前"；但所有模型都缺一个**显式、持久、可验证的对象级状态**。MolmoAct2 的 pointing/depth 是最接近的，但它仍是"每帧推理"，不是"跨帧对象图 + 步骤裁判"。

### 0.4 32k / 169h 的真实规模：不是 32k 条轨迹，而是约 1800 万帧

官方：32 任务、32,000 演示、169 小时、四路相机（head stereo L/R + wrist L/R）、30fps、LeRobot v3（[S1][S9][S34]）。粗算：

- 169h × 30fps ≈ **18.25M 个时间步**；×4 视角 ≈ **73M 张图**。
- 若 1 fps 抽帧：608k 时间步；×4 视角 ≈ **2.43M 张图**——约 20× COCO 检测集。
- 若 5 fps：3.04M 时间步；×4 视角 ≈ **12.2M 张图**——约 100× COCO。

这意味着：**数据规模的天花板不在 episode 数，而在我们愿意为每帧标多少对象/部件/关系。** 32k 条轨迹是固定的；但对象级监督可以从 32k 变成 60 万–1200 万帧。这是本轮"数据规模"的核心机会。

### 0.5 对象中心方法的证据链已经足够硬

- **OBEYED-VLA**：显式对象中心 + 几何 grounding，在 clutter 下提升语言条件视觉 grounding；结论是"把感知做成显式对象组件是增强 VLA 泛化的有效方式"（[S27]）。
- **LiLo-VLA**：对象中心 VLA 处理"只含目标对象的局部视图"，对无关视觉特征和空间构型不变；仿真 69% 平均，比 π0.5 +41%（[S28]）。
- **SlotVLA**：用 slot 表示对象-关系，LIBERO+ 上验证对象关系推理（[S29]）。
- **Microsoft**：对象中心残差 RL，冻结 VLA + 对象中心状态，真机 42%→76%（[S30]）。
- **Harness VLA**：冻结 VLA + 解析原语做 grounding/staging/release，把语义重定位和非接触阶段交给 planner（[S31]）。
- **π0.5**：训练中显式使用 object detections；Interleaved-VLA 也指出视觉 grounding 错误（错物、漏检、框不全）是主要失败模式之一（[S21][S36]）。
- **MolmoAct2**：把 object detection/pointing 放进 3.3M 具身推理语料（[S11]）。

这些不是 UniBot 上的直接证据，但方向一致：**显式对象/部件 grounding 是当前 VLA 的短板，也是可迁移的增益来源。**

### 0.6 数据规模的经验：多样性/覆盖 > 纯数量；精度任务更吃数据

- **Data Scaling Laws**（40k 演示、15k 真机 rollout）：泛化大致随环境数、物体数呈幂律；"更多环境/物体"比"同环境更多演示"更有效（[S32]）。
- **Curse of Precision**：高精度任务的数据需求呈更陡的 scaling law；闭环/验证可以替代一部分数据（[S33]）。
- **Spirit**："Clean Data Is the Enemy of Great Robot Foundation Models"——数据多样性/速度比"洗干净"更重要（[S18]）。
- **DreamZero**：同一模型，重复数据 33% vs 多样数据 50%（[S15][S40]）。
- **GigaBrain-0**：用 world model 生成 37.3k 小时异构数据，说明"数据引擎"本身是竞争力（[S23][S25]）。

结论：UniBot 的 32k 不算大，但**覆盖 5 个泛化轴的对象/场景多样性**更关键；如果我们能自动测量并补齐覆盖，效果可能好于再采一批同分布演示。

### 0.7 机器人竞赛的统计现实：10 次/任务，噪声比想象大

每个任务 10 次（5 轴 ×2）。在 p≈0.3 时：

| 统计单元 | n | SE | 95% CI 半宽 |
|---|---:|---:|---:|
| 总体（32 任务 ×10） | 320 | 2.6pp | ±5.0pp |
| 单轴（32 任务 ×2） | 64 | 5.7pp | ±11.2pp |
| 单任务（10 次） | 10 | 14.5pp | ±28.4pp |
| 单任务单轴（2 次） | 2 | 32.4pp | ±63.5pp |

所以：**榜首 29.7% 与第二 28.5% 的 1.2pp 差距完全在噪声里；不要根据榜单小差距做架构选择。** 反过来，任何 <5pp 的"提升"都很难在官方评测里稳定复现；应该追求 >5–10pp 的稳健增益，或用配对/分层分析提高功效。这也意味着上一轮"单轴 +15pp"的算术要谨慎：单轴只有 64 次，估计本身有 ±11pp 的噪声。

## 1. 三个灵感词，各自钉到事实上

### 1.1 目标检测：不是加一个检测器，而是把"评分步骤"变成可计算谓词

UniBot 的 5 个泛化轴——位置、干扰物、背景、未见物品、人为干扰——本质上都是**对象级**的：目标在哪、哪个是目标、旁边多了什么、背景变了还能不能找到、目标被移动后还认不认得。VLA 的隐式注意力在这些轴上会漂移；显式检测/分割/跟踪给出对象 ID、掩码、3D 位置、关系，正好补这个洞。

但"检测"在这里不是 COCO 式的 80 类框。UniBot 需要的是：

- **任务条件检测**：语言给出"红积木 / 绿盘子 / 插头 / 网口 / 拉链头 / 瓶盖"，检测器要在候选里选对，而不是只输出大类。
- **部件级检测**：把手、杯沿、盖子、锁孔、拉链头、插头尖端、注射器针头、相框支架。抓取点和插入点往往在部件上，不在物体中心。
- **多视角 3D 融合**：头双目给全局，腕部给局部；透明试管、注射器、网线在单视角下不稳，需要深度/边缘/多视角一致性。
- **时序跟踪与对象永久性**：人为干扰会把物体移走/拿走；对象图要能检测"预期位置 vs 实际位置"的冲突，并重新 grounding。
- **不确定性**：检测置信度 + 多视角一致性 + 时序稳定性；低置信度时触发主动视角调整，而不是盲抓。

这五件事合起来，才是"目标检测"在 UniBot 里的正确形态。它既是**输入接口**（对象 token / 锚点），也是**输出裁判**（步骤谓词），还是**数据标注器**（离线自动标注）。

### 1.2 数据规模：不是更多 episode，而是更多"每帧监督 + 覆盖"

32k 条轨迹是官方给的，大家都一样；再采 2–3 倍同分布数据，边际收益递减（Data Scaling Laws 的结论）。真正的杠杆是：

- **每帧多任务监督**：对象框/掩码、部件、关系、步骤进度、接触/抓取状态。32k 轨迹 → 60 万–1200 万帧级标签。
- **覆盖审计**：统计每个任务的对象实例、颜色、位置、背景、干扰物、未见物品覆盖；找出长尾，主动补。
- **反事实合成**：用分割把目标/干扰物抠出来，合成到新背景/新位置/新光照；每个合成场景都有精确标签，专门打 5 个轴。
- **检索上下文**：32k 演示作为测试时上下文库（K 条），不增加训练参数，但增加"可用数据"。
- **世界模型合成**：GigaBrain 式生成数据，成本高，作为 P2/P3。

所以"数据规模"应该改写成 **effective data scale = 监督密度 × 覆盖度 × 反事实多样性 × 检索可用性**。这比"32k 够不够"更有操作性。

### 1.3 机器人竞赛：成功率优先 + 高方差 + 任务组合

规则已经明确：成功率优先，步骤分破同分。于是：

- **不要为了步骤分牺牲成功率**。一个 30% 成功 / 39 步骤分的模型 > 29% 成功 / 45 步骤分的模型。
- **步骤分仍然是训练信号**：它给出稠密的部分完成度，适合做辅助损失、数据筛选、失败诊断；但不是排名目标。
- **高方差**：10 次/任务；单任务 CI ±28pp；不要按单任务榜单过拟合。总体 320 次 CI ±5pp；追求大增益。
- **任务组合**：32 个任务等权；一个任务从 17%→27% 与另一个从 30%→40% 对总平均的贡献一样。应该按"每单位投入的边际成功增益"分配，而不是只看最弱任务。
- **提交策略**：同分看提交日期；如果允许多次提交，先交稳定版再迭代；如果不允许，等到有 >5pp 把握再交。提交次数/规则是开放问题。
- **可靠性**：180s、重置、多机、远程 API；对象图/裁判可以在超时前触发重试/恢复，减少"卡死到 180s"的失败。

## 2. 榜单头部解剖：为什么都停在 30% 以下

我把八个模型按"公开架构 + 数据 + 可能强项 + 可能在 UniBot 上失手的地方"排了一张表（表在产物区 §1.3）。这里先给结论：

1. **没有唯一赢家**：榜首 MolmoAct2 强在空间推理，第二 Wall-OSS-0.5 强在广谱本体，第三 DreamZero 强在物理动力学；它们代表三种不同的归纳偏置。榜单的 1–3 名差距 1.8pp，远小于噪声。
2. **共同短板是"对象级状态 + 步骤验证"**：MolmoAct2 的 pointing/depth 是每帧的；Wall-OSS 的 VLA 是端到端的；DreamZero 的视频世界模型是像素级的。三者都没有一个跨帧持久、可查询、可验证的对象/部件图。
3. **失败集中在后段**：占位榜的步骤分普遍比成功率高 6–12pp；高差距任务（ColorArrangement、OrganizeTools、PackDoll、PaperCupStacking）都是"前面能做、最后一步/最后几步倒"的类型。这与"终局放置是闸门"一致，但也说明**前段 grounding 一旦错，后面全错**；检测/裁判要覆盖全过程，不只终局。
4. **任务×模型交互很大**：HangCup 的成功率跨模型 9.0–38.4%，PlacePhotoFrames 17.6–42.0%，PlugCharger 16.5–38.2%。这说明架构/数据配方在特定任务上差异很大；一个通用感知层如果能把这些"模型敏感"的任务拉齐，收益可能比换底座更大。
5. **外部基准说明 30% 不是天花板**：Spirit-v1.5 在 RoboChallenge Table30 上 50.33%，DM0.5 也在 2026-10 登顶；UniBot 更难（人形 G1 + Dex1 + 5 轴 + 32 任务），但 30% 不是物理极限，是当前方法的极限。

**假设（可证伪）**：如果把失败分成"目标/容器 grounding 错、接近/抓取错、放置/插入错、释放/稳定错、没发现失败"五类，那么前两类 + 最后一类合计占一半以上；对象/部件检测 + 步骤裁判能直接吃掉这三类的一部分。若在离线 held-out 上对象 grounding 准确率提升 10pp 而端到端成功率不涨，则假设不成立，回退到纯策略改进。

## 3. 主判断：SCOPE-GPR

一句话：**不要把目标检测当成 VLA 前面的一个预处理，而要把它做成单 checkpoint 内的对象/部件图 + 步骤谓词裁判；用它把 32k 演示变成千万级对象级监督，并在推理时守住每一步的成功闸门。**

四个组件：

- **ODA（Object/Part Detection Adapter）**：单 checkpoint 内的检测/分割/部件 query head；离线用 Grounding DINO + SAM2 做教师，在线只跑学生头。多视角 3D 融合 + 跟踪 + 不确定性。
- **SGM（Scene Graph Memory）**：对象/部件节点、属性、3D 位姿、关系、状态（抓取/放置/插入/打开/闭合）、置信度；跨帧持久，人为干扰后更新。
- **SPV（Score-step Predicate Verifier）**：把 32 任务的官方 `score_steps` 翻译成对象图上的谓词；训练时给 32k 演示打步骤进度标签，推理时做"前进/重试/回退/恢复"。
- **DSE（Data Scale Engine）**：1 fps/关键帧自动标注、步骤标签、反事实合成、覆盖审计、scaling ladder。把"数据规模"从 episode 数变成监督密度/覆盖度。

再加一个 **CPS（Competition Portfolio Scheduler）**：成功率优先、噪声感知、任务组合、提交策略。它不是模型，是竞赛策略层。

**为什么这比"再换一个更大的 VLA"更划算？**

- 头部模型的预训练数据已经是 720h–37k 小时；UniBot 只给 169h。再换底座，边际收益有限。
- 头部模型的共同短板是对象级状态/步骤验证；这是接口/数据问题，不是参数量问题。
- 对象级监督可以从同样的 32k 里"无中生有"出 10–100× 标签；这是唯一不依赖新采集的 scale lever。
- 成功率优先的规则下，步骤裁判直接服务于"守住成功闸门"；这比优化步骤分更对齐排名。

**可证伪的预测**：

- 离线：对象/部件检测在 held-out 对象上 mAP@0.5 ≥ 0.6；步骤谓词 F1 ≥ 0.8。
- 在线：在 T10/T26（插入）、T19/T31（拉链）、T27（堆叠）、T05/T12（拔出/开锁）上，终局步成功率 +10pp 以上；总体 +5pp 以上。
- 如果 E1（仅辅助检测、不进推理）不涨、E2（对象 token 进推理）不涨、E3（裁判进推理）才涨，说明增益主要来自验证/恢复，而不是感知表示；这也是可接受的结论，会调整主线。
- 如果三者都不涨，说明瓶颈在动作/数据/本体，回退到基线 + 纯工程可靠性。

## 4. 方案轮廓（细节在产物区）

```text
离线：
32k demos (4 cams, 169h)
  ├─ 教师检测/分割（Grounding DINO + SAM2）→ 对象/部件 track
  ├─ 官方 score_steps → 步骤谓词 → 每帧步骤进度标签
  ├─ 反事实合成（背景/位置/干扰物/未见物）→ 带标签场景
  └─ 覆盖审计（对象/关系/轴）→ 数据配比

单 checkpoint：
shared VLM backbone
  + object/part query head（检测/分割/部件）
  + relation/step head（关系/步骤进度）
  + action expert（flow matching / DiT）
  + anchor head（放置/插入位姿）

在线：
language → task/step graph → object/part graph → anchors
  → VLA action chunk
  → predicate verifier → advance / retry / recover
  → human-interference monitor → re-ground / re-plan
```

关键工程约束：

- **单模型合规**：检测/分割/关系/步骤/动作全部在同一个 checkpoint 内；教师模型只离线用；场景图和谓词是确定性代码。模型卡写清楚。
- **异步**：检测/图更新 5–10Hz，动作 10–30Hz；只在关键帧（抓取前、释放前、每 chunk 结束）跑重检测，控制延迟。
- **回退**：透明/布料/小件检测置信度低时，回退到深度/边缘/颜色分割 + VLA 隐式注意力；不要硬依赖检测。
- **预算**：180s；每个任务按步骤数/权重分配重试；长程任务（T16/T17/T31）最多 1 次重试；终局步优先。

## 6. 风险与合规（先立后破）

- **单模型审计**：检测头必须是同一 checkpoint 的一部分；教师模型只离线；图谱/谓词是确定性代码。若官方认定检测头算第二个模型，退化为"VLA 自身 pointing 输出 + 确定性图"。
- **检测在透明/反光/小件上失效**：多视角 + 深度 + 边缘 + 颜色；任务特定部件检测；置信度低时回退。
- **自动标注噪声**：多视角/时序一致性 + 1–2% 人工抽检 + conformal 校准；步骤谓词 F1 不达标就不上线。
- **延迟**：异步 + 关键帧 + 模型蒸馏/量化；p99 目标 <100ms（若 API 允许更宽，可放宽）。
- **数据规模幻觉**：先做 scaling ladder；如果加标签不涨，说明动作数据/策略容量是瓶颈，及时回退。
- **竞赛噪声**：10 次/任务；不要追 <5pp 的榜单差异；用 320 次总体 + bootstrap；追求大增益。
- **规则未读部分**：外部数据/合成数据是否允许、提交次数、单模型定义边界，仍需邮件确认；默认不依赖外部数据。
- **榜单占位**：不要把 29.7% 当真实基线；真实榜单发布后重跑假设。

## 7. 一句话押注

**把目标检测升级成"单 checkpoint 内的对象/部件图 + 步骤谓词裁判"：用它把 32k 演示变成千万级对象级监督，并在推理时守住每一步的成功闸门；这比再换一个更大的 VLA 或再采一批演示更可能把成功率从 30% 推到 40%+。**

| 单任务单轴 | 2 | 32.4pp | ±63.5pp | 几乎不可用于归因 |

**竞赛策略含义**：
- 1–3 名 1.8pp 的差距在噪声内；不要模仿"榜首的小技巧"。
- 追求 >5–10pp 的稳健增益；用 320 次总体 + bootstrap/配对设计。
- 单任务/单轴榜单只用于失败挖掘，不用于模型选择。
- 步骤分是连续量，方差可能小于成功率，适合做训练信号/诊断，但排名仍看成功率。

### 1.8 事实/推断分界

| 事项 | 状态 |
|---|---|

## 2. 为什么都停在 30% 以下：失败分解与假设

### 2.1 评分算术（修正版）

```text
排名键 = (总平均成功率, 总平均步骤分, 提交日期)
成功率 = 所有步骤完成的 episode 比例（终局步是闸门）
步骤分 = Σ 步骤权重 × P(该步完成)（仅破同分/训练信号）
```

上一轮把"步骤分 59.7% 是放置类"当作优化目标；本轮修正为：**放置/插入/终局仍是成功率的闸门，所以仍是第一优先；但不要为了多拿部分分而牺牲完成全任务的概率。** 例如，一个保守但能完成终局的策略，优于一个前段多拿 10 分但终局经常失败的战略。

### 2.2 五类失败模式与检测/裁判杠杆

| 失败模式 | 典型任务 | 对象/部件检测 + 步骤裁判能做什么 | 预期杠杆 |
|---|---|---|---|
| F1 目标/容器 grounding 错 | T01 HangCup、T04 FruitSorting、T06 ColorArrangement、T21 ArrangePlates、T25 StoreCups | 任务条件检测选对目标；关系谓词确认"哪个盘子/哪个槽位"；多视角消除歧义 | 高 |
| F2 接近/抓取错 | T03 PackDoll、T08 Bookshelf、T11 Battery、T17 Stationery、T30 PinnedNote | 部件检测（把手/杯沿/边缘）；3D 抓取点；抓取后状态验证 | 中高 |
| F3 放置/插入错 | T10 PlugCharger、T26 PlugInEthernet、T05 DisconnectEthernet、T32 Syringe、T07 PhotoFrame | 插头尖端/网口/针头/支架部件检测；深度/插入谓词；位姿锚点 | 高 |
| F4 释放/稳定错 | T20 PaperCup、T27 StackBowls、T29 PackPhone | settle-verify；稳定性谓词；nudge/regrasp | 中 |

**假设 H1**：F1 + F5 合计占失败的一半以上；对象/部件检测 + 步骤裁判能把这两类的一部分转成成功。
**假设 H2**：F3 的插入/拔出类任务对"部件级检测 + 深度/接触谓词"最敏感；这是最值得做真机 A/B 的子集。
**假设 H3**：F6 不能靠纯检测解决；必须保留 VLA 隐式通路，检测只做辅助/验证。

### 3.2 ODA：单 checkpoint 内的对象/部件检测适配器

**设计目标**：不引入第二个推理模型；检测/分割/部件/关系/步骤/动作共享一个 backbone。

**输入**：
- 4 路 RGB（head stereo L/R、wrist L/R），按任务裁剪/缩放；
- 语言指令（5 条复述之一）；
- 本体感觉（关节/EE/夹爪/lower body）；
- 任务对象词表（从语言 + 官方任务描述生成）。

**结构（两种实现，按底座选）**：
- **Option A（首选）**：MolmoAct2 式 backbone，原生 pointing/detection；增加 object query head（N=64）、part query head（M=32）、relation/step head、action expert。检测/pointing 能力来自预训练，微调成本低。
- **Option B（回退）**：WLA-1.0-Base（6B，Apache-2.0，24GB 可微调）或 Wall-OSS-0.5（4B）；加 DETR/Mask2Former 风格的 query head；LoRA 微调 backbone。

**输出**：
- 每个对象：2D box、mask logits、object embedding、类别/属性、置信度；
- 每个部件：部件类别（handle/rim/lid/slot/tip/slider/keyhole/stand）、2D 点/框、3D 位置、置信度；
- 关系：left/right/front/back/above/below/on/in/next-to/stacked/inserted；
- 状态：grasped/placed/open/closed/zipped/locked/upright/stable；
- 步骤进度：当前 score_step 的 soft label。

**多视角 3D 融合**：
1. 用头双目的深度/视差把 2D 框/掩码反投影到 3D；
2. 用外参把腕部视角的局部观测融合进来；
3. 对每个对象维护 3D 中心/包围盒/朝向 + 置信度；
4. 用 Kalman/ByteTrack 做时序跟踪；遮挡时用上一次状态 + 机器人本体运动预测；
5. 多视角重投影误差 > 阈值 → 降置信度，触发主动视角调整/重检测。

**不确定性**：
- 检测分数 + mask IoU 一致性 + 多视角重投影误差 + 时序稳定性；
- 用 held-out 演示做 conformal 校准，给出"这个对象/部件是否可信"的阈值；
- 低置信度时：
  - 优先用另一视角/腕部近景；
  - 用深度/边缘/颜色分割补充；
  - 仍不确定 → 回退到 VLA 隐式注意力 + 保守动作（不要盲抓）。

**为什么部件级**：
- 抓取点通常在把手/杯沿/边缘，不在物体中心；
- 插入点在插头尖端/网口/针头/锁孔；
- 拉链/盖子/支架的状态在部件上（slider/lid/stand）；
- 部件级检测比完整 6D 更便宜、更稳，尤其对透明/形变物体。

### 3.3 SGM：场景图记忆

**节点**：
- 对象：`id, label, attributes(color/shape/material), 3D centroid, bbox, orientation, mask, confidence, track_age`
- 部件：`id, parent_object, part_label, 2D point/box, 3D position, confidence`
- 区域/容器：`id, label, polygon/3D region, capacity, occupied_by`
- 机器人：`EE pose, gripper state, joint state`

**边**：
- 空间：left/right/front/back/above/below/on/in/next-to/touching；
- 功能：handle-of、lid-of、slot-of、container-of、plug-of、tip-of；
- 任务：target、receptacle、distractor、obstacle、unseen；
- 时序：moved-by-human、removed、reappeared。

**状态机**：
- 每个对象/部件有状态：`free → grasped → in-hand → placed/inserted → stable`；
- 每个步骤有状态：`pending → in-progress → done → regressed`；
- 人为干扰：对象图检测到"预期位置/状态 vs 实际观测"冲突 → 标记 `regressed` → 触发恢复。

**查询 API**（确定性）：
```python
graph.find("red block")            # 任务条件检索
graph.relation("bowl2", "on", "bowl1")
graph.state("zipper_slider")       # open/closed/position
graph.anchor(step)                 # 放置/插入锚点
graph.changed_since(t)             # 人为干扰检测
```

### 3.4 SPV：步骤谓词裁判

**谓词库**（按任务类别）：

| 类别 | 任务例子 | 谓词 |
|---|---|---|
| 抓取/放置 | T01–T04, T06, T08, T13, T15, T17, T20–T22, T24, T25, T27, T30 | `grasped(obj)`, `in(obj, region)`, `on(obj, support)`, `stacked(top, bottom)`, `upright(obj)`, `stable(obj, 0.5s)`, `color_match(obj, plate)`, `ordered(seq)` |
| 插入/拔出 | T05, T10, T26, T32 | `tip_inside(plug, socket)`, `insertion_depth > d`, `lateral_error < ε`, `contact_stable`, `pulled_out(cable)`, `liquid_transferred` |
| 关节/闭合 | T07, T09, T12, T14, T18, T19, T23, T28, T29, T31 | `lid_open/closed`, `stand_open`, `key_turned`, `lock_open`, `cap_removed`, `zipper_closed`, `case_closed` |
| 形变 | T16, T19, T23, T31 | `fold_line`, `corner_pair`, `towel_folded`, `pouch_closed` |
| 顺序/分类 | T04, T06, T15, T21, T22, T24, T25 | `left_to_right_order`, `color_group`, `category_match`, `letter_on_board` |

**步骤标签生成**：
1. 对每条演示，按 1 fps + 关键帧（夹爪开合、EE 速度突变）采样；
2. 用 SGM 计算每个谓词的真值/置信度；
3. 用 HMM/动态规划平滑，得到步骤进度曲线；
4. 对齐官方 `score_steps` 的步骤边界；
5. 人工抽检 1–2%，校准阈值。

**推理时**：
```python
def scope_step(task, step, obs, graph, budget):
    for attempt in range(budget + 1):
        anchors = graph.anchor(step)
        ctx = retrieve(step, graph, k=4)
        for chunk in policy.act(obs, anchors, ctx, step):
            send(chunk)
            graph.update(obs)                  # ODA + 跟踪 + 关系
            if graph.predicate(step):           # 步骤完成
                return True
            if graph.regressed(step):           # 人为干扰/对象被移动
                graph = re_ground(obs, task)
                break
            if stalled(obs, graph, 2.0):        # 无进展
                break
        if not graph.predicate(step):
            recover(step, graph)                # nudge/regrasp/retry
    return graph.predicate(step)
```

**为什么裁判是"研究贡献"而不是"工程 trick"**：
- 它把官方评分步骤变成**免费的稠密监督**：每帧都有步骤进度标签；
- 它让失败 rollout 变成**部分成功数据**：最高完成步骤就是部分分，可做 hindsight relabeling；
- 它让推理从"开环执行"变成"闭环验证"，直接对齐成功率闸门；
- 它是**任务无关**的：谓词库可复用到 32 任务，不需要每任务一个模型。

### 3.5 DSE：数据规模引擎

**目标**：把 32k 条轨迹变成 60 万–1200 万帧级对象/部件/关系/步骤监督，并测量覆盖。

**流水线**：

```python
for episode in dataset:
    frames = sample_keyframes(episode, fps=1, grasp_events=True)
    dets = teacher.detect(frames, vocabulary=task_objects)
    tracks = sam2.propagate(frames, dets)
    graph = fuse_multiview(tracks, calib)
    steps = evaluate_predicates(graph, task.score_steps)
    save(episode, graph, steps)
    coverage.update(graph)

# 学生 head 训练
for batch in labeled_frames:
    loss = L_det + L_seg + L_part + L_rel + L_step
    update(object_head, part_head, relation_head)

# 反事实合成
for scene in sampled_scenes:
    objects = segment(scene)
    new_scene = compose(objects, new_background, new_positions, new_distractors)
    verify(new_scene, predicates)
    save(new_scene)
```

**标注预算**：
- 教师检测：Grounding DINO 1.5/2.0 或 YOLO-World；分割：SAM2.1；
- 1 fps 全量：608k 时间步，×4 视角 ≈ 2.43M 图；
- 关键帧（抓取/释放/步骤边界）：每 episode 5–10 帧，32k × 8 ≈ 256k 帧；
- 人工抽检：1–2% 分层抽样（按任务/对象/难度）；
- 学生 head：在 100k–300k 帧上训练，蒸馏教师 + 人工纠正。

**覆盖审计**：
- 对象实例/类别/颜色/材质；
- 位置分布（桌面网格、容器区域）；
- 背景/桌布/光照；
- 干扰物类型/数量；
- 未见物品的替代类别；
- 人为干扰剧本（官方备注）；
- 每个任务/轴的覆盖热力图。

**反事实合成**：
- 目标：位置轴、干扰物轴、背景轴、未见物品轴；
- 方法：分割目标/干扰物 → 合成到新背景/新位置/新光照 → 用检测/谓词验证标签 → 软权重混入训练；
- 风险：合成伪影/物理不合理 → 用 GF 软权重 + 真实混采 + 教师复核；
- 规模：10–20k clips（不是 10 万小时）；目标是覆盖长尾，不是替代真实。

**Scaling ladder**：
| 实验 | Episode 数 | 标签密度 | 目的 |
|---|---:|---|---|
| L0 | 1k | 0 | 低数据基线 |
| L1 | 4k | 0 | 数据量曲线 |
| L2 | 16k | 0 | 接近全量 |
| L3 | 32k | 0 | 全量基线 |
| L4 | 4k | 1 fps 对象/步骤 | 监督密度能否替代数据量 |
| L5 | 16k | 1 fps | 中等数据 + 密集标签 |
| L6 | 32k | 1 fps | 全量 + 密集标签 |
| L7 | 32k | 1 fps + 反事实 | 覆盖/反事实的增益 |

**预测**：L4 应接近 L2/L3 的一部分；若 L4 无增益，说明动作数据/策略容量是瓶颈，DSE 降级为离线工具。

### 3.6 CPS：竞赛组合调度

**目标**：在成功率优先、10 次/任务、高方差的榜单上，做任务组合与提交策略。

**输入**：
- 本地/调试槽的每任务成功率 $p_i$、步骤分 $s_i$、方差；
- SCOPE 的每任务边际增益 $\Delta_i$（离线/小样本真机）；
- 任务成本 $c_i$（数据/工程/调试槽）；
- 检测难度 $d_i$（透明/小件/关节/形变）。

**启发式优先级**：
```text
priority_i ≈ (1 - p_i) × max(s_i - p_i, 0) × d_i × model_spread_i / c_i
```
- 只作为排序启发式，不做精确优化；
- 避免 p_i > 60%（天花板）或 p_i < 5%（可能不是同一瓶颈）的任务；
- 用 Bayesian bandit / Thompson sampling 在调试槽上分配；
- 每次只改一个变量，避免 10 次/任务的噪声淹没效果。

**提交策略**：
- 同分看提交日期；如果平台保留早期提交，先交稳定版占位；
- 如果只保留最新/最终提交，等到 >5pp 把握再交；
- 提交次数/规则未核实 → 默认"一次强提交 + 一次修正"；
- 提交前 soak：N 端口并发、状态隔离、健康检查、p99 延迟、reset 行为。

### 3.7 与 GPR-VLA 的接口与损失

```text
L = L_action
  + λ1 L_obj      # 检测框/类别
  + λ2 L_seg      # 掩码
  + λ3 L_part     # 部件点/框/类别
  + λ4 L_rel      # 关系谓词
  + λ5 L_step     # 步骤进度（soft label）
  + λ6 L_ver      # 成功/失败/恢复
  + λ7 L_anchor   # 放置/插入锚点
```

| 项 | 含义 | 起始权重 |
|---|---|---:|
| L_action | flow matching / 动作 chunk | 1.0 |
| L_obj | 检测（box + class） | 0.2 |
| L_seg | 分割（mask） | 0.1 |
| L_part | 部件（点/框/类别） | 0.1 |
| L_rel | 关系（多标签 BCE） | 0.1 |
| L_step | 步骤进度（BCE/回归） | 0.2 |
| L_ver | 成功/失败/恢复（BCE） | 0.1 |
| L_anchor | 锚点/位姿（L1/L2） | 0.1 |

**训练时必须注入推理同分布的噪声**：
- 检测框/掩码的抖动、丢失、误检；
- 对象图置信度的 dropout；
- 人为干扰造成的状态跳变；
- 否则推理期第一次见到不完美图会崩。

**单 checkpoint 合规**：
- 所有 head 共享 backbone；教师模型只离线；
- 场景图/谓词是确定性代码；
- 模型卡写清楚：backbone、heads、教师、离线标注、检索库、确定性模块；
- 如果官方认定检测 head 是第二个模型 → 退化为"VLA 自身 pointing + 确定性图"。

### 3.8 可选 OWM：对象中心世界模型

**动机**：DreamZero 证明视频世界模型能提升物理泛化，但 14B/7Hz 太重；UniBot 的步骤/对象结构更适合**对象图转移**而不是像素预测。

**设计**：
- 输入：当前 SGM + 动作 chunk；
- 输出：下一个 SGM（对象位置/关系/状态）；
- 结构：小 transformer（100–300M）或同一 checkpoint 的 head；
- 训练：32k 演示的 SGM 序列；
- 用途：
  - 训练时：预测步骤进度/成功，做辅助监督；
  - 推理时：比较"预测图 vs 实际图"，提前发现失败；
  - 规划时：对候选 chunk 做短程 rollout，选谓词最可能满足的。
- 优先级：P2/P3；先做 ODA+SGM+SPV，OWM 作为下一轮扩展。

## 4. 数据引擎（DSE 细节）

### 4.1 自动标注流水线

| 阶段 | 输入 | 方法 | 输出 | 质量控制 |
|---|---|---|---|---|
| 抽帧 | 32k episodes | 1 fps + 夹爪开合/EE 速度突变关键帧 | 608k–1M 帧 | 每任务分层 |
| 教师检测 | 帧 + 任务词表 | Grounding DINO / YOLO-World | 2D 框/类别 | 置信度阈值 |
| 教师分割 | 框/点 prompt | SAM2.1 | 掩码 | mask IoU 一致性 |
| 跟踪 | 视频 + 首帧掩码 | SAM2 video / ByteTrack | 对象 track | 时序一致性 |
| 3D 融合 | 多视角 + 标定 | 三角化/深度反投影 | 3D 中心/bbox | 重投影误差 |
| 关系 | SGM | 几何谓词 | 关系标签 | 规则 + 抽检 |
| 步骤 | 官方 score_steps | 谓词库 | 步骤进度 | HMM 平滑 + 抽检 |
| 覆盖 | 全量 | 统计 | 覆盖热力图 | 长尾清单 |

### 4.2 步骤标签与 hindsight relabeling

- 对每条演示，生成每帧的步骤进度向量 $q_t \in [0,1]^K$；
- 对失败 rollout，最高完成步骤 $k^*$ 作为部分成功标签；
- 用 $k^*$ 做 hindsight relabeling：把"失败"转成"完成了前 k* 步"的训练样本；
- 这样每个 rollout（成功/失败）都能贡献步骤监督，数据效率更高；
- 风险：谓词误判 → 用双阈值/人工抽检/一致性检查。

### 4.3 反事实合成

| 轴 | 做法 | 标签 | 风险 |
|---|---|---|---|
| 位置 | 移动目标/容器到新位置 | 新 3D 坐标/关系 | 物理不合理/遮挡 |
| 干扰物 | 插入额外物体 | 干扰物 mask/关系 | 遮挡目标 |
| 背景 | 替换桌布/纹理/光照 | 背景标签 | 颜色偏移/反光 |
| 未见物品 | 替换同类不同外观 | 新对象标签 | 形状/材质差异过大 |
| 人为干扰 | 按官方备注移动/拿走/撤销 | 状态变化/恢复标签 | 剧本编号含义未核实 |

**合成比例**：真实 : 合成 ≈ 80:20 到 70:30；不要合成主导。用 GF 软权重；每批混入真实。

### 4.4 覆盖审计与数据配比

- 每个任务/轴一张覆盖表：对象实例数、颜色数、位置网格覆盖、背景数、干扰物类型数、未见物品替代数；
- 找出"覆盖低 + 成功低"的任务/轴 → 优先补；
- 找出"覆盖高 + 成功低"的任务/轴 → 可能是策略/动作瓶颈，不是数据；
- 用覆盖度加权采样，避免简单重复多数场景。

### 4.5 数据规模杠杆对比

| 杠杆 | 有效规模 | 成本 | 风险 | 优先级 |
|---|---|---|---|---|
| 密集对象/部件标签 | 10–100× 监督 | 8×H100 1–2 周 | 标签噪声 | P0 |
| 步骤进度标签 | 18M 弱标签 / 608k 强标签 | CPU + 人工抽检 | 谓词误判 | P0 |
| 反事实合成 | 5–10× 视觉多样性 | 8×H100 1 周 | sim2real gap | P1 |
| 检索上下文 | K 条演示/测试时 | 缓存/ANN | 延迟 | P1 |
| 外部实验室数据 | 2–3× 背景/位置 | 协调/合规 | 规则未明 | P2 |
| 世界模型合成 | 10×+ 小时 | 很高 | 幻觉/物理错 | P3 |
| 更多同分布演示 | 2–5× | 很高 | 实验室偏差 | P3（不可控） |

## 6. 推理与竞赛运行时

### 6.1 推理循环

```python
def run_episode(task, obs):
    graph = SGM(task)
    step = 0
    t0 = time()
    while step < len(task.steps) and time() - t0 < 175:
        budget = budget_for(task, step, time() - t0)
        ok = scope_step(task, step, obs, graph, budget)
        if ok:
            step += 1
        else:
            if not recoverable(task, step, graph):
                break
            graph = re_ground(obs, task)
    return task.score(step, graph)
```

### 6.2 重试/恢复预算

| 任务类型 | 例子 | 最大重试 | 说明 |
|---|---|---:|---|
| 短程（2–3 步） | T01, T10, T27 | 2 | 终局步优先 |
| 中程（4 步） | T09, T15, T18, T28 | 1–2 | 按剩余时间 |
| 长程（5 步） | T16, T17, T31 | 1 | 避免超时 |
| 插入/拔出 | T05, T10, T26, T32 | 2 | 最值得闭环 |
| 形变/拉链 | T16, T19, T23, T31 | 1 | 检测不稳，保守 |

### 6.3 人为干扰监控

- 每 0.2–0.5s 比较 SGM 的预测状态 vs 实际检测；
- 如果目标对象位置/状态发生非机器人引起的变化：
  - 暂停当前 chunk；
  - 重新检测/定位目标；
  - 若对象被拿走/不可见 → 搜索/等待/改变计划；
  - 若对象被移动 → 更新锚点/位姿，继续；
  - 若步骤被撤销（如拉链被拉开、盖子被拧回）→ 回退步骤；
- 用官方 `human_1_note` / `human_4_note` 作为离线测试剧本（编号含义未核实，但内容可用）。

### 6.4 API/延迟/重置

- `reset()` 每 episode 清空 SGM/缓存/状态机；
- 多端口并发：状态隔离、无全局变量、健康检查；
- 异步：检测/图更新 5–10Hz；动作 10–30Hz；只在关键帧重检测；
- p99 目标 <100ms（若官方 API 允许更宽，可放宽）；
- 超时保护：175s 停止新步骤，留 5s 收尾；
- 日志：每步时间戳、谓词、对象图快照、动作 chunk；离线复盘。

### 6.5 提交策略

- 成功率优先；步骤分只破同分；
- 同分看提交日期；如果平台保留早期提交，先交稳定版；
- 如果不确定，默认"一次强提交 + 一次修正"；
- 提交前 soak：N 端口、并发、reset、网络抖动、延迟；
- 模型卡：底座、heads、教师、离线标注、检索库、确定性模块、单模型声明。

## 8. 创新点清单（持续迭代；动机/差异/可行性/资源/步骤/风险/状态）

> 状态说明：押注=本轮主线；保留=沿用；升级=旧点被改造；降级=保留但不再是主回路；砍=不做。

### 8.1 本轮主押注（新增/升级）

#### I14 ODA：单 checkpoint 对象/部件检测适配器（新增，押注）
- **动机**：5 个泛化轴本质是对象级；头部模型缺显式、持久、可验证的对象/部件状态；检测是把 32k 变成千万级监督的最便宜接口。
- **与现有方案差异**：不是外挂检测器/第二个模型；检测/分割/部件/关系/步骤/动作共享一个 backbone；部件级而非仅物体框；多视角 3D + 跟踪 + 不确定性。
- **技术可行性**：MolmoAct2 原生 pointing/detection 可复用；WLA/Wall-OSS 可加 DETR/Mask2Former head；Grounding DINO+SAM2 可离线做教师；32k 数据足够训练任务特定 head。
- **所需资源**：8×H100 3–5 天教师标注；100k–300k 帧学生训练；SAM2/Grounding DINO 许可核对；1–2 人。
- **落地步骤**：抽帧 → 教师标注 → 多视角融合/跟踪 → 学生 head → 与 VLA 联合训练 → 离线 mAP/真机验证。
- **风险**：透明/反光/小件检测失败 → 深度/边缘/颜色回退；单模型审计 → 同 checkpoint/模型卡披露；标签噪声 → 抽检/conformal。
- **状态**：押注，P0。

#### I15 SGM：场景图记忆（新增，押注）
- **动机**：VLA 的隐式注意力是每帧的；人为干扰/遮挡/长程任务需要跨帧持久状态；步骤裁判需要一个可查询的世界状态。
- **与现有方案差异**：对象/部件节点 + 关系 + 状态 + 置信度 + 时序；不是像素级世界模型，也不是纯文本状态机；确定性代码，可审计。
- **技术可行性**：几何谓词 + 检测/跟踪即可；3D 融合用头双目深度/标定；复杂状态（拉链/盖子）用小型 head。
- **所需资源**：标定/外参；CPU/轻量 GPU；1 人。
- **落地步骤**：节点/边 schema → 多视角融合 → 跟踪/遮挡预测 → 关系/状态谓词 → 查询 API → 与 SPV 接线。
- **风险**：检测错误传播 → 置信度门控/多视角一致性；状态谓词误判 → 双阈值/人工抽检；延迟 → 关键帧更新。
- **状态**：押注，P0。

#### I16 SPV：步骤谓词裁判（由 I1 SSG 升级，押注）
- **动机**：官方 score_steps 是免费的稠密监督；成功=全步骤；推理需要"前进/重试/回退/恢复"的裁判。
- **与现有方案差异**：谓词由对象图计算，不是文本匹配/纯状态机；训练时给 32k 演示打步骤标签，推理时做闭环；失败 rollout 可 hindsight relabel。
- **技术可行性**：32 任务步骤已公开；谓词库可覆盖大多数任务；复杂状态用小型 head；人工抽检 1–2%。
- **所需资源**：CPU + 少量人工；无需新数据。
- **落地步骤**：解析 score_steps → 谓词库 → 每帧标签 → HMM 平滑 → 裁判接线 → 真机 A/B。
- **风险**：谓词 F1 不够 → 只保留高置信步骤；长程任务误判 → 双阈值/预算守卫；规则变化 → 版本化。
- **状态**：押注，P0。

#### I17 DSE：数据规模引擎（由 I10 TLE/ACP/GF 升级，押注）
- **动机**：32k 固定；有效数据规模 = 监督密度 × 覆盖 × 反事实 × 检索；检测让每帧变成多任务监督。
- **与现有方案差异**：不只是"合成数据"；是"自动标注 + 步骤标签 + 覆盖审计 + scaling ladder"的闭环；用官方评分步骤做标签，不是自由仿真。
- **技术可行性**：教师模型成熟；1 fps 抽帧可控；反事实合成用分割+合成；覆盖审计是统计。
- **所需资源**：8×H100 1–2 周；存储 10–20TB；人工抽检。
- **落地步骤**：抽帧 → 教师标注 → 学生 head → 步骤标签 → 反事实 → 覆盖审计 → scaling ladder。
- **风险**：标签噪声/合成伪影 → 抽检/GF 软权重/真实混采；数据规模幻觉 → ladder 证伪。
- **状态**：押注，P0。

#### I18 CPS：竞赛组合调度（新增，中优先）
- **动机**：成功率优先、10 次/任务、高方差；不能按单任务榜单过拟合；任务/轴/提交需要组合策略。
- **与现有方案差异**：把"竞赛"当研究变量：噪声感知、任务杠杆、调试槽 bandit、提交策略；不是纯工程。
- **技术可行性**：规则明确；本地/调试槽可估 p_i/Δ_i；bootstrap/贝叶斯简单。
- **所需资源**：评测预算/调试槽；1 人。
- **落地步骤**：建立任务表 → 估 p_i/方差 → 算杠杆 → 分配调试槽 → 记录 → 迭代。
- **风险**：调试槽稀缺/规则变化 → 保守；占位榜误导 → 只用真实数据。
- **状态**：保留/中优先，P1。

#### I19 OWM：对象中心世界模型（可选，P2/P3）
- **动机**：DreamZero 证明世界模型有用但 14B 太重；对象图转移更轻、更可解释；可用于失败预警/规划。
- **与现有方案差异**：预测对象/部件图状态，不预测像素；与 SPV 共享表示；可作为同一 checkpoint 的 head。
- **技术可行性**：32k 演示的 SGM 序列可训练小 transformer；推理开销低。
- **所需资源**：8×H100 数天；1 人。
- **落地步骤**：SGM 序列 → 小 transformer → 预测下一个图 → 失败预警/短程 rollout。
- **风险**：图噪声/误差累积 → 只做预警不做主控；数据不足 → 先离线。
- **状态**：stretch，P2。
