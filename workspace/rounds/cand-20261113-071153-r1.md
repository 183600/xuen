# 灵感循环 v3（承接 v2）· 「具身智能大模型」×「语义地图」——从“像素到动作”到“绑定到地图”：把泛化改写成对象绑定与进度记账问题

> **直觉先行。** 一个 VLA 大模型真正擅长的，不是记住 32 条轨迹，而是“见过很多物体、听得懂语言、知道杯子该抓把手”。它缺的不是“会做”，而是三件更具体的事：**对哪个实例做**、**它在空间里的锚点在哪**、**现在做到第几步、进度有没有被人反向撤回**。语义地图恰好补这一层：它不是给机器人导航用的 SLAM 地图，而是模型跨 chunk 的**外部工作记忆**——负责实例身份、空间锚点、关系/属性与进度账本。本轮把 v2 的“验证-重做”升级为 **“地图绑定 → 对象相对动作 → 地图差分记账”** 的闭环，旗舰是 **SGM-VLA（Semantic-Graph-Map VLA）**。

**三条硬修正，直接决定本轮方案形态：**

1. **不能靠“运行时改块长”换反应性。** v2 的 UIP-13 ACS“声明最大 k、实际返回更短块”不成立；`T_a` 是编译期常量。反应性只能靠“离线选更小的全局 `T_a`”与“块内动作设计”换。

## 2. 两个灵感词的直觉解释

### 2.1 具身智能大模型：它给的是“会做”的先验，缺的是“绑定”

**直觉**：请一位见过很多厨房、听过很多指令的老师傅。他知道“抓杯子要抓把手”“插头要对准插座”“叠毛巾要先铺平”。但你把他放进一个**新桌子**，他仍要先看一眼：哪个是杯子、哪个是插座、现在毛巾叠到哪一步。大模型给的是**技能先验**，不是**当前场景的绑定**。比赛里 32 个任务、5 类泛化，真正卡人的正是绑定：物体换了位置、背景变了、出现没见过的物体、完成到一半被人撤回。**大模型负责“会做”，语义地图负责“对谁做、做到什么程度”。**

**严谨表述**：把策略写成 `π_θ(a_{1:T_a} | o, l)`。预训练 VLA 提供的是跨任务的条件先验 `p_θ(skill | l, object appearance)`；它没有显式变量来表示“当前 episode 中语言所指的实例 `i*`、其锚点 `μ_i*`、当前计分步 `v`”。SGM-VLA 显式引入这三个变量，把策略改写成
`π_θ(a_{1:T_a} | M_t, l, q_t)`，其中 `a` 是**对象相对动作**，`M_t` 是地图。这样，大模型参数只需学习“给定对象局部外观与关系，如何操作”，而不必把“物体在哪、进度到哪”烧进权重。

### 2.2 语义地图：不是导航地图，而是策略的“外部工作记忆 + 账本”

**直觉**：人做长任务时会用工作记忆记账：“杯子已经放进碗里了，下一步拿第二个。”机器人只有 4 路相机、没有深度、物体还会被手挡住；如果每个 chunk 都从零看世界，就会反复确认、重复动作、也发现不了“刚才的进度被撤回了”。语义地图就是那张**跨 chunk 的账本**：记住有哪些物体、谁在谁上面、盖子开没开、拉链拉没拉、上一步是否真的完成了。它不需要毫米级准确，但必须**知道自己有多不确定**。

**严谨定义（OCSM，对象中心语义地图）**：在块边界 `t`，
`M_t = ⟨O_t, R_t, Γ_t, A_t⟩`
- `O_t = {o_i}`：对象槽。`o_i = (id_i, role_i, label_i, z_i, μ_i, Σ_i, attr_i, status_i)`；`role_i ∈ {target, receptacle, tool, distractor, fixture, hand}`；`label_i` 来自开放词表；`z_i` 是外观嵌入；`μ_i ∈ R^3, Σ_i` 是 base frame 锚点及其协方差；`attr_i` 是开合/满空/折叠/拉链等属性；`status_i ∈ {visible, occluded, missing}`。
- `R_t ⊆ O_t × O_t × P`：关系边，`P = {on, in, left_of, front_of, stacked_on, inserted, aligned, near, holding}`。
- `Γ_t`：**动态附着图**。当夹爪闭合且接触目标时，加边 `(hand_h, o_i)`，此后 `o_i` 的锚点改为“相对手”而非“相对世界”；释放时再重锚到世界。没有这张图，“物体相对动作”在抓取后会双重计数。
- `A_t`：每个槽的锚点坐标系与不确定度；可选 2D 关键点。

**与 SLAM 的区别**：我们不追求全局一致的地图；我们追求**身份、关系、属性、进度、不确定度**这五样。语义地图在这里是“策略的账本”，不是“导航的地图”。

## 3. 严谨定义与两个关键命题

### 3.1 地图相对动作参数化（MRAP）

设目标物 `o_i` 的锚点坐标系为 `F_i = T_{B←i}`（base frame 到物体 frame），夹爪 frame 为 `E`。策略预测**物体相对动作**
`u = (T_{i←E}^{target}, g_cmd, p_cmd)`，
再经地图变换为 base frame 命令：
`T_{B←E}^{target} = F_i · T_{i←E}^{target}`。
若 `o_i` 正被夹持（`Γ_t` 中有 `(hand_h, o_i)`），则用抓取瞬间固定的 `T_{E←i}^{attach}`：
`F_i = T_{B←E}^{current} · T_{E←i}^{attach}`，
释放后再用最后一次 `F_i` 把物体重锚回世界。`joint` 模式下再解 `q_target = IK(T_{B←E}^{target})`。

### 3.2 命题 1（刚性场景变换下的不变性）

**命题**：若场景只发生 base frame 下的刚性变换 `g ∈ SE(3)`（位置整体移动、桌子转向等），且物体局部外观不变，则最优的**物体相对动作** `u*` 不变；base frame 动作按 `T'_{B←E} = g · T_{B←E}` 等变。因此，学习 `p(u | 对象局部特征, 关系, l)` 的策略**不需要把 `g` 学进权重**，只需让地图锚点 `F_i` 承载它。

**证明草图**：`T_{B←E} = F_i · T_{i←E}`；变换后 `F_i' = g F_i`，而物体相对目标 `T_{i←E}` 不变，故 `T'_{B←E} = g F_i T_{i←E} = g T_{B←E}`。策略输入若只依赖物体局部特征与关系（对 `g` 不变），则输出 `u` 不变。
**边界条件**：相机固定在机器人上，物体投影外观会随位置变化（透视、遮挡），所以“对象局部特征对 `g` 不变”只是近似；用多视角裁剪 + 地图空间增强（UIP-20）把它逼近。背景/干扰物不是 `g` 的刚性变换，由“裁剪式 token + 角色绑定”处理，而非本命题覆盖。

### 3.3 地图差分进度验证（MDPV）

对每个计分步 `v`（与 `scoring_points` 一一对应），定义地图谓词 `φ_v: M → {0,1,⊥}`，`⊥` 表示当前视角不可观测。块边界上计算
`C_v(t) = φ_v(M_t)`，`L_v(t) = max_{s≤t} C_v(s)`（latch，曾经达成）。
- **推进**：`C_v: 0→1`。
- **撤回**：`C_v: 1→0`（人扰的典型形态）。
- **不可观测**：`φ_v = ⊥` ⇒ 用代理谓词或**构造式验证**（做一个不破坏进度的小探针动作，让状态变得可见）。

### 3.4 命题 2（计分语义未定时的重做占优）

**命题**：在两种未核实的计分语义下——`H_final`：`S = Σ_v w_v C_v(T)`；`H_latch`：`S = Σ_v w_v L_v(T)`——对“被撤回的步 `v` 执行重做、把 `C_v` 恢复到 1”这一决策，其步骤分收益在 `H_final` 下严格为正，在 `H_latch` 下为 0；两种情况下都不为负（忽略时间成本）。因此，**基于地图差分的重做策略对计分语义是稳健的**。

**证明**：`H_final` 下，重做把 `C_v(T)` 从 0 恢复到 1，收益 `w_v>0`；`H_latch` 下，`L_v` 已为 1，重做不改变 `L_v`，收益 0。成功率的论证同理：若成功看最终状态则重做有益，若成功也 latch 则中性。唯一成本是时间与再次被干扰的风险，由 UIP-19 的重做预算约束。
**这个命题很重要**：它把“计分语义未核实”从“方案可能归零的风险”降级为“收益大小的不确定性”。

### 3.5 可观测性审计（本轮的方法论约束）

不是所有计分步都能从 4 路 RGB 直接看出。对每个 `φ_v` 标注：
- **直接可观测**：物体在/不在、堆叠关系、开合角度、拉链滑块位置；
- **间接可观测**：插入深度（用连接器-端口重叠 + 停留时间代理）、液体转移（用针管活塞位移 + 倾角代理）、盖子拧紧（用相对朝向 + 夹爪-盖分离代理）；
- **不可观测**：内部液体真实体积、接触力大小、被完全遮挡的内部状态 ⇒ 必须用构造式验证或直接放弃该谓词的精细判断，退回“步骤推进”的粗粒度。

## 4. 瓶颈假设（v3）

- **H1（最高杠杆）**：5 类泛化里，位置/背景/干扰物/未见物体主要不是“低层技能不够”，而是**绑定错误**；策略把“抓杯子”绑定到错误的实例或错误的空间锚点。显式地图 + 对象相对动作能把这类错误从“模型容量问题”变成“感知/关联问题”。
- **H2（结构性）**：`T_a` 固定、观测只在块边界到达 ⇒ 人为撤回的检测延迟有下界。地图的价值不是“更快看到”，而是“在看不到的时候仍记得”，从而在下一个边界立刻发现“状态被改回去了”。
- **H3（被低估）**：无 depth/基座位姿/力觉 ⇒ 地图锚点有噪声。必须把不确定度 `Σ_i` 显式传入策略，并在 `Σ_i` 大时退回“绝对动作 + 重新观测”，而不是盲目相信地图。
- **H4（效率）**：4 路全图 ≈ 6k visual tokens；用地图选 4–8 个对象裁剪，可把 token 降到 ~2k，直接改善单卡 N 端口并发的延迟与抖动。地图既是泛化机制，也是算力机制。
- **H5（风险）**：地图由同一骨干在线估计，误差会与策略误差相互放大；这是本轮最大威胁，必须用“离线教师伪标签 + 地图噪声训练 + 真机/Gazebo 锚点”三重约束。

## 5. v3 清单与押注（详见产物区）

围绕两词发散多份草案，合并后得到 **UIP-16~22（7 项）**：旗舰 **UIP-16 SGM-VLA**，核心腿是 **UIP-17 OCSM**（地图）、**UIP-18 MDPV**（差分验证）、**UIP-19 MTA**（token/延迟）、**UIP-20 MSA**（地图空间造数据）、**UIP-21 ORG**（角色绑定）、**UIP-22 MOC**（标定与可观测性审计）。v2 的 UIP-02（计分表）保留为谓词与分值来源；UIP-11 GSO 退为地图真值夹具；UIP-13 的“运行时变块长”被纠错删除。

**→ 本轮最值得押注**：**UIP-16 + UIP-17 + UIP-18 的“地图绑定闭环”**——它把 v2 已经命中的“人扰反向撤回”与“计分步有序”两条规则事实，统一到同一个可计算对象（地图状态差分）上；同时用对象相对动作对准位置/背景泛化，用 token 选择对准延迟。它不需要额外传感器、不需要运行期外部大模型，完全落在选手的离线算力与提交 API 之内。

---

## 6. 本轮最大风险

**一句话**：语义地图由同一骨干在线估计、且缺少深度/基座位姿/力觉，地图误差会与策略误差相互放大；若不能在代表任务上把对象/关系/撤回检测的精度压到可用阈值，整套“对象相对动作”就会退化为更慢、更脆的绝对策略。

# 灵感循环 v3 产物 · UniBot 创新点清单 v3（UIP-16~22）

> 承接 v2 的 UIP-01′~15。本轮为**换表示层，不是换任务**：保留 v2 已核实的“32 任务计分点 + 人扰反向撤回 + 开环动作块 + N 端口隔离”四条主线，把“手写谓词验证”升级为“对象中心语义地图 + 地图差分记账”，把“绝对像素到动作”升级为“对象相对动作”。事实来源与检索日期见想法区 §0。
> **合规底线**：提交物只有一个 checkpoint、一条共享骨干；语义地图是**非参数数据结构**，不是第二个模型；离线教师（分割/开放词表/VLM）只在训练期使用，**不进入运行期**。

## 1. 旗舰：UIP-16 · SGM-VLA

### 1.1 总体架构（单 checkpoint）

```text
obs_t（固定键：4×RGB + 双臂关节/EE/夹爪 + lower_body + language）
   │
   ├─> [UIP-17 OCSM]  槽关联 → 锚点更新 → 关系/属性 → 附着图 → 不确定度
   │        │
   │        ├─> [UIP-18 MDPV]  地图差分：推进 / 撤回 / 不可观测
   │        └─> [UIP-19 MTA]   选对象裁剪 + 全局低分辨率上下文 + 腕部接触图
   │
   ├─> [共享骨干]（视觉编码器 + 语言 + 地图关系 token + 本体 token）
   │        ├─> 动作头：对象相对动作 u=(T_{i←E}, gripper, pivot)
   │        └─> 辅助头：地图增量 / 撤回分类 / 锚点不确定度（训练期为主）
   │
   ├─> [MRAP 变换]  u + F_i（或抓取附着）→ base frame EE（或 IK→joint）
   └─> [UIP-19 护栏] 动作平滑 / 重做预算 / 延迟预算 → 返回 (T_a, …)
```

**关键设计**：地图不是“又一个编码器”，而是把“实例身份、锚点、关系、进度”从视觉 token 里**抽取成显式变量**，再以少量图 token 回灌给同一个骨干。这样骨干的容量用于“技能”，地图负责“绑定”。

### 1.2 单次 `get_action` 的伪代码

```python
class SGMVLA_Policy:
    def __init__(self, backbone, map_updater, verifier, allocator, governor,
                 task_schema, T_A, K_MAX_REDO=2):
        self.bb = backbone; self.mu = map_updater
        self.vf = verifier; self.al = allocator; self.gov = governor
        self.schema = task_schema          # 32 任务计分步 + 谓词 + 权重
        self.T_A = T_A                     # 握手期固定，绝不返回短块
        self.redo = 0

    def reset(self):
        self.M = None; self.s = self.vf.init_state()   # 地图 + 计分状态
        self.redo = 0; self.last_chunk = None; self.bb.reset()

    def get_action(self, obs):
        # 1) 地图更新（块边界只做一次）
        self.M = self.mu.update(self.M, obs, self.last_chunk)
        # 2) 地图差分记账（推进/撤回/不可观测）
        diff = self.vf.diff(self.M, self.schema, obs.language)
        self.s = self.vf.update_belief(self.s, diff)      # 保留 latch 与 current 两套账
        # 3) 选 token（对象裁剪 + 全局上下文 + 腕部）
        tokens, anchors = self.al.select(self.M, self.schema, obs.language)
        # 4) 单骨干前向：对象相对动作块
        u_chunk, aux = self.bb.forward(tokens, anchors, obs, self.s,
                                       T_a=self.T_A)
        # 5) 对象相对 → base frame（或 IK→joint）
        a_chunk = self.bb.to_base(u_chunk, self.M, obs)
        # 6) 安全/可信度护栏
        a_chunk = self.gov.smooth(a_chunk, self.M, self.s, self.redo)
        self.last_chunk = a_chunk
        return a_chunk                    # 形状严格 (T_A, …)

    def on_chunk_end(self, obs_next):
        # 评测端执行完整块后才会再次调用；撤回只能在下一个边界被看到
        pass
```

> 注意：`get_action` 每次必须返回 `T_a` 步；不能因为“想快点重观测”而返回更短块。反应性来自**离线选更小的 `T_a`** 与**块内动作设计**，不是运行期变长。

## 2. UIP-17 · OCSM：对象中心语义地图

### 2.1 数据结构与更新

```python
Slot = {
    "id": int, "role": str,        # target / receptacle / tool / distractor / fixture / hand
    "label": str,                  # 开放词表标签（可多标签）
    "z": Tensor[d],                # 外观嵌入，用于跨帧关联
    "mu": Tensor[3], "Sigma": Tensor[3,3],   # base frame 锚点 + 不确定度
    "attr": dict,                  # open/closed, full/empty, folded, zipped, inserted...
    "status": str,                 # visible / occluded / missing
    "last_seen": int
}
Map = {"objects": [Slot], "relations": [(i,j,p,conf)],
       "attach": [(hand, i, T_E_i)], "base_shift": g, "step_belief": s}
```

**单次更新**（块边界）：
1. **检测/分割候选**：用骨干视觉特征 + 蒸馏出的轻量 proposal/mask 头；离线教师（SAM/GroundingDINO/开放词表检测器）只用于生成训练标签。
2. **槽关联**：外观 `z` + 空间门控 `Mahalanobis(μ_i, Σ_i)` 做匈牙利匹配；新实例开新槽，连续 `missing` 超过阈值则标记 `missing`（不是删除，供撤回检测用）。
3. **锚点更新**：可见时用多视角几何（左右高位 + 腕部，需 UIP-22 的标定）三角化/光束法平差；不可见时用“最后一次锚点 + 动作传播”预测，并增大 `Σ_i`。**没有 depth 时不要伪造高置信 3D**：`Σ_i` 必须诚实地大。
4. **关系/属性**：轻量头从对象裁剪 + 相对几何判 `on/in/stacked_on/inserted/open/closed/...`；输出置信度，低置信写 `⊥`。
5. **全局刚体位移检测（RSD）**：对相邻两帧的锚点集合做 **2D/2.5D RANSAC 刚体拟合** `g`（无深度时不强行升 3D）。若 `g` 能解释大多数锚点（残差小、内点比例高），判为**基座/场景整体移动**，把地图重表达到新 base frame；若只有少数锚点移动，判为**物体级干扰**。这是在无 IMU、无显式基座位姿条件下，用地图本身充当“里程计代理”的关键技巧；其可信度必须由 `Σ_i` 与内点比例共同门控。
6. **附着图**：夹爪闭合 + 接触目标 ⇒ 加 `(hand_h, o_i)` 边并记录 `T_{E←i}^{attach}`；释放 ⇒ 删边，用最后一次 `F_i` 重锚。抓取后的对象相对动作必须走“手相对”，否则会双重计数。

### 2.2 标定与降级（UIP-22）

- **理想**：用 URDF/一次性标定得到 `T_{B←cam}`（高位相机刚性固定在机器人上）。若数据/手册提供了相机内外参，直接使用并锁版本。
- **降级 A**：没有标定时，地图退化为**关系图 + 腕部相对锚点**：不输出 `μ_i` 的绝对 3D，只输出“在目标物 frame 下的相对位姿”与“左右/前后/上下”序关系。MRAP 仍然可用（相对动作不依赖绝对 3D）。
- **降级 B**：连腕部相对都不可靠时，`Σ_i` 设为很大，`MDPV` 只保留“对象存在/消失/堆叠关系”这类粗谓词；策略退回绝对动作，并把“重观测”频率提高（离线选更小 `T_a`）。

### 2.3 可观测性审计表（代表任务）

| 任务 | 计分步谓词 | 可观测性 | 代理/构造式验证 |
|---|---|---|---|
| T16 FoldTowel | 铺平→折第一折→折第二折→压实 | 直接/间接 | 巾面轮廓面积 + 折边位置；压实用夹爪停留+高度代理 |
| T19 ZipUp | 对齐→拉链啮合→拉到底 | 间接 | 两片布边缘间距 + 滑块位置；拉到底用“滑块到端点 + 停留” |
| T26 PlugInEthernet | 抓线→对准→插入 | 间接 | 连接器-端口 2D 重叠 + 插入方向 + 停留；无 force，用“轻拉不脱”作构造式验证 |
| T27 StackBowls | 放第一→叠第二→叠第三 | 直接 | `stacked_on` 关系 + 碗口中心距 |
| T32 SyringeWaterTransfer | 抽液→移液→注液 | 不可直接 | 活塞位移 + 针筒倾角 + 液面可见时的颜色/体积代理；否则只判“抽/注动作完成” |
| T12 Unlock | 对准→转动→拔锁 | 间接 | 锁体朝向变化 + 锁与架分离；中途“锁被拿走”用 `missing` 槽 + 关系消失 |

**结论**：不要宣称“所有计分步都能验证”。MDPV 的诚实形态是：**直接谓词给强信号，间接谓词给弱信号，不可观测谓词只做粗粒度推进/撤回检测**；三者都带置信度，交给 UIP-19 的预算决策。

## 3. UIP-18 · MDPV：地图差分进度验证

### 3.1 谓词与双账本

对任务 `τ` 的计分步集合 `V_τ`（与 `scoring_points` 对齐，`K≤5`，权重 `w_v` 合计 100）：

```python
def map_diff(M_prev, M_now, schema):
    out = []
    for v in schema.steps:                 # 有序
        c_prev = eval_predicate(schema.phi[v], M_prev)   # 0/1/⊥
        c_now  = eval_predicate(schema.phi[v], M_now)
        if c_prev == 0 and c_now == 1: out.append(("advance", v))
        elif c_prev == 1 and c_now == 0: out.append(("regress", v))
        elif c_now == 0 and c_prev == 0: out.append(("ongoing", v))
        elif c_now == 1 and c_prev == 1: out.append(("done", v))
        else: out.append(("unobservable", v))
    return out
```

维护两套账：
- `current[v] = C_v(t)`：当前状态；
- `latch[v] = max_{s≤t} C_v(s)`：曾经达成。
两套账的差值就是“**被撤回的步**”：
`regressed[v] = latch[v] and not current[v]`。
由于命题 2，重做在 `H_final` 下严格加分、在 `H_latch` 下不扣分；所以决策只需看“重做成本是否在预算内”，不需要先确定计分语义。

### 3.2 决策规则（带预算）

```python
def decide(diff, s, schema, redo_budget, latency_left):
    for kind, v in diff:
        if kind == "regress" and s.latch[v]:
            if redo_budget > 0 and latency_left > schema.cost[v].redo_ms:
                return ("redo", v)        # 优先恢复出现倒退的、分值最高的步
        if kind == "advance":
            s.advance(v)
    # 没有倒退：按计分表推进；末步分值更大 ⇒ 保前置、搏末步
    return ("continue", next_incomplete(s, schema))
```

**优先级**：`regressed` 中按 `w_v` 从大到小排序；同一 `T_a` 内最多重做 `K_MAX_REDO` 次（建议 2）；若延迟预算不足，宁可放弃重做也不要拖垮可信度。

### 3.3 构造式验证（针对 `⊥`）

对不可观测谓词，允许一次低风险“探针动作”，例如：
- 插入类：轻拉 2–3 mm，看是否脱开（不脱开 ⇒ 已插入）；
- 盖子类：轻微反向拧，看相对朝向是否跟随（不跟随 ⇒ 已拧紧）；
- 堆叠类：轻抬 1–2 mm，看下层是否跟随（跟随 ⇒ 已叠上）。
探针必须满足 `expected_score_gain > probe_time_cost + regression_risk`；否则不探。

## 4. UIP-19 · MTA：地图 token 分配与延迟护栏

### 4.1 算力推导（设计期估算，非实测）

以 ViT patch=14 为例：
- 4 路 480×640 全图：`4 × ceil(480/14) × ceil(640/14) = 4 × 35 × 46 ≈ 6.4k` visual tokens；
- 全局低分辨率上下文（160×120）：`12 × 9 ≈ 108` tokens；
- `m` 个任务相关对象裁剪（224×224）：`m × 16 × 16 = 256m` tokens；
- 腕部接触裁剪（224×224）：`256` tokens；
- 语言 + 地图关系/属性 + 本体：约 `80–150` tokens。

取 `m=6`：`108 + 1536 + 256 + ~120 ≈ 2.0k` tokens，约为全图的 **1/3**。若接触密集步只把“活动对象”提到 320×320（`23×23=529`），总 token 仍 < 2.5k。**这是设计期估算；真实延迟必须用同一硬件、同一 batch、同一端口并发数实测。**

### 4.2 token 选择规则

```python
def select_tokens(M, schema, lang):
    roles = ground_roles(lang, M)          # UIP-21
    must = [o for o in M.objects if o.role in ("target","receptacle","tool")]
    must += [o for o in M.objects if o.id in schema.active_set]
    # 变化大 / 不确定 / 刚被撤回的对象优先
    score = lambda o: (o.attr_changed * 2 + trace(o.Sigma) + o.recency)
    picked = topk(must + sorted(M.objects, key=score, reverse=True), k=m)
    return crops(picked), anchors(picked)
```

### 4.3 握手期配置（`obs_delta_indices` / `image_resize` / `T_a`）

这三项在握手期一次确定，运行期不能按 chunk 改。因此做**离线配置搜索**：在验证集上枚举
`T_a ∈ {4, 8, 16, 32}`、图像缩放 `{240×320, 320×400, 480×640}`、堆叠帧 `{1, 2, 3}`，
以“成功率约束下的 p95 延迟 + 抖动”为目标选一组全局配置。**不要**在运行期返回短块或改键。

### 4.4 每端口隔离与可信度

- 每个端口独立 `Map`、`step_belief`、`redo` 计数、历史缓存；共享骨干只做**无状态批处理**，KV/历史不得跨端口复用。
- 护栏：动作平滑（限幅/低通）、重做次数上限、延迟预算；避免“地图抖动 → 动作抖动 → 统计规律性异常”。
- 若地图更新导致动作突变（例如 RSD 误判基座移动），用 `Σ_i` 门控：不确定度高时退回“保持当前动作 + 下一块重观测”，而不是猛跳。

## 5. UIP-20 · MSA：地图空间造数据（离线）

公开 32 数据集约 3.2 万条成功演示（按 v2 记录），但**没有**“位置/背景/干扰物/未见物体/人为撤回”的系统覆盖。MSA 用对象级编辑补前四类，Gazebo/真机脚本补第五类。

| 泛化轴 | MSA 做法 | 成本 | 备注 |
|---|---|---|---|
| 位置 | 用实例 mask 抠出目标物，inpaint 原位置，按新位姿粘贴（缩放/旋转/透视/阴影匹配） | 低 | 直接扩位置分布；保持语言角色不变 |
| 背景 | 替换桌面/背景纹理、光照、相机轻微抖动 | 低 | 与位置增强组合 |
| 干扰物 | 粘贴其他任务的物体作为 distractor，不改变指令指代 | 低 | 训练“角色绑定”而非“类别匹配” |
| 未见物体 | 用其他任务/其他数据集的同类/异类实例替换目标物，保留角色与语言 | 低-中 | 需 UIP-21 的角色标注 |
| 人为撤回 | 用 Gazebo 脚本或真机脚本复现“拧回/翻开/拉开/拿走/挪底座”，生成 `(前态→撤回→恢复)` 三元组 | 中 | 2D 编辑难以物理正确地“撤回”，不要硬造假数据 |

**离线教师**：SAM/GroundingDINO/开放词表检测器用于生成 mask 与伪标签；它们**只在训练期运行**，不进入提交物。合成图需做物理合理性过滤（阴影方向、遮挡顺序、接触点），否则会教坏策略。

## 6. UIP-21 · ORG：开放词表角色绑定

- **角色集合**：`target`（要被操作的）、`receptacle`（容器/目的地）、`tool`（工具）、`distractor`（干扰物）、`fixture`（固定物）、`hand`。
- **绑定函数**：`role_i = g_θ(l, z_i, affordance_i)`；语言解析出“动词 + 目标角色 + 容器角色”，再用对象外观/可供性打分匹配，而不是匹配封闭类别名。
- **未见物体**：即使 `label_i` 是 `unknown`，只要角色被绑定，MRAP 仍可在其锚点 frame 下操作；这是“未见物体”轴上比类别分类更稳的路径。
- **训练**：用公开数据 + MSA 的角色标注；把离线 VLM 的角色判断蒸馏成骨干上的轻量头（单 checkpoint）。

## 7. 训练目标与数据配方

单模型多任务训练，损失：
```text
L = L_BC
  + λ1 · L_map      # 预测下一块的关系/属性变化（地图前向）
  + λ2 · L_undo     # 给定 (M_t, M_{t+1})，判哪一步被撤回
  + λ3 · L_contrast # 同一对象跨视角/跨帧的槽嵌入一致
  + λ4 · L_smooth   # 动作时序平滑（可信度）
  + λ5 · L_anchor   # 有伪标签时的锚点回归（可选）
```
- **地图噪声训练**：训练时对 `μ_i` 加噪声、随机丢弃槽、随机把关系置 `⊥`，让策略学会“地图不准时退回绝对动作/重观测”，避免测试期地图误差直接击穿策略。
- **教师强制 → 调度采样**：先用离线教师伪标签的地图训练，再逐步换成模型自己估计的地图，缩小训练/测试分布差。
- **单骨干**：所有头共享视觉-语言骨干；地图更新头与动作头是同一骨干上的轻量 adapter/head，符合“单模型多任务”。

## 8. 实验设计（E201–E211）

| 实验 | 对照 | 指标 | 目标/证伪条件 |
|---|---|---|---|
| E201 | 无地图 VLA vs SGM-VLA | 位置/背景留出集成功率、步骤分 | 若位置留出集无提升，H1 不成立 |
| E202 | 绝对动作 vs MRAP | 位置/基座移动下的成功率 | 若 MRAP 不优于绝对动作，命题 1 的工程价值存疑 |
| E203 | 无验证 vs 几何验证 vs MDPV | 人扰脚本下步骤分、撤回检测 F1 | 若 MDPV F1 < 0.5，地图谓词太弱，需回到 UIP-22 |
| E204 | token 预算 m=2/4/6/8 | 成功率 vs p95 延迟/抖动 | 若 m=6 比全图掉 >2%，回退全图或提高活动对象分辨率 |
| E205 | 无 MSA vs MSA | 干扰物/背景/未见物留出集 | 若 MSA 只涨训练集不涨留出集，说明合成有偏 |
| E206 | 封闭类别 vs ORG | 未见物体成功率 | 角色绑定应显著优于类别匹配 |
| E207 | 单端口 vs N=3 共享骨干 | 延迟均值/方差、超时率 | 方差应下降；每端口状态必须零共享 |
| E208 | 端到端（16+17+18+19+20+21+22） | 综合成功率+步骤分+可信度 | 相对基线的 Δ 由真机/代理实验给出 |
| E209 | 可观测性审计 | 直接/间接/不可观测谓词占比 | 若不可观测 >40%，方案需重设计谓词 |
| E210 | 标定扰动 | 外参误差 vs 成功率/地图精度 | 量化“无标定”降级的边界 |
| E211 | 计分语义 `H_final` vs `H_latch` 离线模拟 | 重做策略的分数差 | 验证命题 2：重做在两种语义下均不劣 |

> 所有真机结论提测前一律标注为“代理/离线结论”；不虚构榜单分数。官方排行榜仍为 Coming Soon（2026-11-13 复核）。

## 9. 设计期估算与预期（明确标注：未实测）

| 项 | 估算 | 依据 | 风险 |
|---|---|---|---|
| 视觉 token 降幅 | 6.4k → ~2.0k（≈3.2×） | patch=14、m=6 的算术 | 裁剪可能丢上下文；需 E204 验证 |
| 单次推理延迟 | 随 token 近似线性下降 | ViT 主导；未计网络/序列化 | 真实瓶颈可能是 JPEG 解码/传输 |
| 位置/背景泛化 | 相对绝对动作有正 Δ | 命题 1 + 裁剪 token | 透视/遮挡破坏不变性 |
| 人扰步骤分 | 撤回后重做可恢复 `w_v` | 命题 2 | 重做耗时、可能再次被撤回 |
| 未见物体 | 角色绑定优于类别匹配 | ORG 设计 | 角色解析错误会放大 |
| N 端口抖动 | 共享骨干 + 批处理 + token 降幅 → 下降 | 工程经验 | 并发调度不当会反升 |

**不写“预期 +30%”这类无法核实的数字**；用“方向 + 证伪条件”代替，等真机/代理实验再填。

## 10. 合规、风险与缓解

| 风险 | 说明 | 缓解 |
|---|---|---|
| **单模型合规** | 地图更新头/动作头是否被算作“多模型”？ | 所有头共享一条骨干、一个 checkpoint；地图是非参数结构；离线教师不部署；必要时把地图头折进骨干 adapter |
| **地图误差放大** | 同一骨干估计地图，错上加错 | 地图噪声训练、`Σ_i` 门控、低置信退回绝对动作、UIP-22 审计 |
| **无深度/无标定** | 锚点精度不足 | 关系图降级 + 腕部相对锚点 + 一次性标定；不伪造 3D |
| **仿真过拟合** | MSA/Gazebo 只在仿真刷分 | 真机时段做锚点；E205 只看留出集 |
| **接口红线** | 短块/错形状/错 token 会被拒 | 严格 `(T_a, …)`、`meta.token`、握手期配置；CI 跑 `example_env` 校验 |
| **可信度** | 地图抖动 → 动作抖动 | 动作平滑、重做预算、延迟预算、每端口隔离 |
| **计分语义未定** | `H_final` vs `H_latch` | 命题 2：重做对两种语义稳健；不把收益建立在单一语义上 |

## 12. 本轮最大风险 & 押注

**一句话**：语义地图由同一骨干在线估计、且缺少深度/基座位姿/力觉，地图误差会与策略误差相互放大；若不能在代表任务上把对象/关系/撤回检测的精度压到可用阈值，整套“对象相对动作”就会退化为更慢、更脆的绝对策略。

**→ 押注：UIP-16 SGM-VLA，以 UIP-17 OCSM 为表示、UIP-18 MDPV 为记账、UIP-19 MTA 为算力约束**——它把 v2 已从规则里读出的“人为撤回”和“计分步有序”两条事实，统一成同一个可计算对象（地图状态差分），同时用对象相对动作对准位置/背景泛化，且完全落在单模型、无额外传感器、选手 API 权限之内。
