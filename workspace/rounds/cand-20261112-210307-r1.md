# 第 1 轮（灵感循环 v2：「碰撞避免」×「位姿估计」）—— 给语义策略加一层「几何接地」：从会碰撞的动作块到可验证的度量行为

> **承接关系**：v1（UIP-01~10）已经把主战场锁定在「选手仅在远端提供 `observation→action` API」的赛事结构里，旗舰是语义层的滚动验证重试。本轮**不推翻** v1，而是补上它最大的空白：VLA 常常「语义正确、几何错误」——抓偏、插歪、撞翻、扫倒。本轮把两个灵感词合成一层**度量几何校正层**，它仍然完全落在 API 权限内，并天然命中「位置 / 背景 / 未见物品 / 人为干扰」四个泛化轴。

## 0. 先钉死接口语义（本轮复核，来源：`unitreerobotics/unibot_submission` README，2026-11-12）

- `get_action(obs)` 每次返回**整段** `T_a` 步动作块，评测器按 0..T_a−1 顺序执行完才再次调用（README §1/§3）。因此**不存在逐帧回调**：任何「执行 k 步再观测」都只能通过把 `action_chunk_size` 设成 k 来实现，**k 就是我们的反应延迟**。v1 伪代码里「内部 buf 逐帧 pop」在真实接口下应改述为「块级滚动」。
- 观测自带 `left/right_arm` 关节（7×2）与 `left/right_ee_pose_gripper_base`（6×2）：这给出一条**在线运动学自检**通道——用已知 G1 模型做 `FK(q)`，与观测 EE 位姿比对残差，可在线发现关节零位 / 符号 / URDF 版本不一致。
- 4 路相机（高位左右 + 双腕）是**位姿估计的物理基础**：高位左右近似立体对给米制深度，腕部给接触前的高分辨近景。
- `obs_delta_indices` 可取过去若干帧 → 无需额外调用即可估计速度，用于人机 TTC 与物体跟踪。
- §6 明确记录延迟及其波动、动作统计规律性。**几何层的成本必须固定且低方差**，不能因每次 ICP 迭代数不同导致抖动。

## 1. 直觉解释（两个词合起来意味着什么）

**碰撞避免的直觉**：桌面双臂任务里，最贵的失败不是「没抓起来」，而是「抓的时候把整盘杯子扫倒 / 两只手相互撞 / 把已经摆好的东西碰乱」。这类失败有**不对称代价**：它会把后续所有步骤分一起清零。因此一个便宜的「碰撞护盾」即使只拦截少数灾难动作，期望收益也远大于它的平均开销。关键洞察：**我们不需要让策略更聪明，只需要让它别做蠢事**。

**位姿估计的直觉**：VLA 擅长「该去碰什么」（语义），不擅长「差 8 毫米、轴偏 5 度」（度量）。而 6D 物体位姿 + 机器人 FK 恰好补上后者：它把「纸杯是否套上」「插头是否插到底」「夹爪与物体是否同轴」变成**可计算的确定命题**，而不是再问一次大模型。于是形成「System-1 语义策略 + System-2 几何裁判」的双过程结构。

**合起来的直觉**：位姿估计把场景变成一个**度量化的、可预测的未来**；碰撞避免在这个未来里做**扫掠体检查与最小修复**。这不是新模型，而是夹在 `get_action` 返回前的**动作块整流器（rectifier）**。

## 2. 严谨定义

**观测与场景信念。** 在块边界 t：
`B_t = (q_t, T^L_{ee,t}, T^R_{ee,t}, {P_i}_{i=1..m}, D_t, H_t)`
其中 `P_i=(T_i∈SE(3), S_i(形状/可供性), Σ_i(协方差))` 为物体位姿包；`D_t` 为立体重建的截断符号距离场（TSDF/ESDF）；`H_t` 为检测到的人手 / 人臂包围体集合。

**位姿估计算子。** `Π:(4 路图像, 相机内外参, q_t, 语言 l) → B_t`，并对每个 `P_i` 输出置信度 `c_i`。多视图一致性约束：同一物体 `i` 的 `T_i` 需同时满足高位双目重投影误差与腕部视图重投影误差；不一致则降低 `c_i`。

**自模型与扫掠体。** 已知 G1 运动学 `FK: q ↦ {link 位姿}`。对动作块 `A=(a_1..a_T)`：
- joint 空间：`q_{t+s}=interp(q_t,a_s)`，扫掠体 `R(A)=⋃_s ⋃_{links} capsule(q_{t+s})`；
- ee 空间：`X_s` 为末端轨迹，需 IK 求 `q_s`（或用包络胶囊保守近似）。

**碰撞风险与安全集。** `ρ(A)=min_{x∈R(A)} sd(x, D_t ∪ H_t)`，以及自碰撞 `ρ_self(A)`。给定安全裕度 `ε>0`：
`Safe_ε(A) ⇔ ρ(A)≥ε 且 ρ_self(A)≥ε`。
（`sd` 为到障碍的符号距离；`ε` 建议 1.5–2.5 cm，按物体易碎 / 堆叠程度分区设定。位姿不确定时用保守裕度 `ε_eff = ε + k·σ`，`k≈2`。）

**安全投影（整流）。** 给定策略块 `A` 与延迟预算 `τ_max`：
`A* = argmin_{A'∈Safe_ε} ‖A'−A‖_W² + β·R_smooth(A')`，`s.t. cost(A')≤τ_max`。
工程上用三层近似求解：① 时间缩放（减小每步位移增量）；② 插入「抬升-绕行-再接近」via-point（沿 ESDF 负梯度方向）；③ 方向投影到最近安全流形。三者按代价递增依次尝试。

**相对位姿伺服。** 目标位姿 `T_g`（抓取 / 预插入 / 插入），当前末端 `T_e`，误差 `E=T_g T_e^{-1}`，`ξ=Log(E)∈se(3)`。校正增量 `ΔX=Exp(αξ)`。输出 `X'_s = X_s ⊕ w(phase,c)·ΔX`，`α∈[0.2,0.4]`，`w` 在运输段为 0、接触前 3–5 帧升到 1。低增益 + 相位门控是为了不与时序策略「打架」。

**几何进度谓词。** `φ_g(B_t)∈{done, fail, ongoing}`，全部是位姿的确定性函数，例如：
- 套叠：`‖center_i−center_j‖<δ_xy` 且相对 z 轴夹角 `<δ_θ`；
- 插入：沿插座轴投影深度 `d∈[d_min,d_max]` 且横向误差 `<δ_lat`；
- 直立 / 倾倒：物体 z 轴与重力夹角、质心高度；
- 归位：物体位姿落在容器凸包 / 区域内。
这类谓词比 VLM 快且可解释；VLM 只处理谓词覆盖不到的语义状态。

**人机 TTC。** 用堆叠帧估计人手速度，常数速度外推 `Ĥ(s)`；机器人预测轨迹 `X(s)`。`TTC=inf{s: dist(X(s),Ĥ(s))≤r_robot+r_human}`。若 `TTC<τ_yield` 则输出让行块（保持 / 回撤 / 暂停），并平滑接回。

## 3. 瓶颈假设（可证伪）

- **H1**：32 任务里相当一部分失败是**几何失败**而非语义失败（抓偏、插歪、碰撞），尤其集中在插接 / 套叠 / 倒液 / 摆盘类。若成立，几何校正层的性价比最高。
- **H2**：**灾难性场景破坏**（扫倒整盘、双臂互撞）在失败中占比不低，且其步骤分损失远大于普通失败；护盾的期望收益主要来自左尾。
- **H3**：透明 / 反光物体（试管、注射器、纸杯）是位姿估计的主要失效源；立体深度 + 腕部近景 + 多视图一致性可显著降低失败率，但仍是瓶颈。
- **H4**：块级几何计算若同步且固定迭代次数，可把每次调用的额外延迟控制在 ~30–50 ms，且方差很小；异步化虽降均值但会放大反应延迟与方差。

## 4. 候选清单（UIP-11~20，详见产物区）

旗舰 **UIP-11 GACR**：动作块级的「扫掠体碰撞护盾 + 相对位姿整流」；其余 9 点分别覆盖几何进度验证、人机让行、跨机标定、抓取方向、滑移监测、透明物体多视图融合、动作一致性护栏、位姿对齐增广、双过程仲裁。清单与 v1 的 UIP-01~10 是**层间互补**：v1 管「做什么 / 何时重试」，本轮管「怎么动才不撞、才对准」。

## 5. 本轮最值得押注

**UIP-11 GACR**：它是唯一同时用上两个灵感词、且对「成功率」与「步骤分」都有直接作用、还不需要碰执行层的点。它把真机上最不可逆的失败（撞翻 / 撞坏）变成可拦截事件。

## 6. 本轮最大风险

**一句话**：GACR 的安全性完全建立在「位姿与运动学足够准」之上——一旦立体标定 / 透明物体位姿 / FK 模型有系统偏差，护盾会把「本来能成的动作」误判为碰撞并强行回撤，反而制造新失败；因此必须用观测自带的 `(q_t, ee 位姿)` 做在线运动学校验、给位姿加置信度门限、并在误报时退化为「只减速不改向」。

## 1. 旗舰点深潜：UIP-11 GACR

**全名**：Geometry-Aware Collision-shielded Rectification（几何感知的碰撞护盾式整流）。

**机制**：在 `get_action(obs)` 内部、返回动作块之前，依次执行：
1. **场景信念构建**：用 4 路相机做位姿估计与立体占据重建，得到 `B_t`；用 `FK(q_t)` 与观测 EE 位姿做在线运动学自检。
2. **扫掠体安全检查**：把策略块 `A` 插值成轨迹，计算整段机器人扫掠体与场景 / 另一只臂的最小符号距离 `ρ(A)`。
3. **三层最小修复**：不安全时按代价递增尝试「时间缩放 → 插入 via-point → 方向投影 / 回撤」。
4. **接触前相对位姿伺服**：仅在接近阶段用物体位姿计算小残差，低增益、相位门控地叠加到动作块。
5. **人机让行与一致性护栏**：见 UIP-13 / UIP-18。

**与现有方案差异**：
- 常见 VLA 直接开环执行整块动作，没有度量安全裁判；纯几何 MPC 又缺乏语义。GACR 把**几何裁判插在语义块与执行之间**，且只做「最小修复」，不重写任务意图。
- 与 v1 的 UIP-01 是不同层：UIP-01 在块边界问「子目标完成了吗」，GACR 在同一块边界问「这段动作会撞吗、对准了吗」。两者共享 `T_a` 这个节奏，可合并成一个 wrapper。

**为什么权限内**：全部逻辑在返回的 `action.*` 数组上完成，不触碰执行层、不修改触发器、不改 ROS；`control_space`、`action_chunk_size`、`obs_delta_indices` 都是选手可声明的元数据。

**控制空间选择**：优先 `joint`——扫掠体检查可用真实关节轨迹，且 `(q_t, T_ee,t)` 可在线校验 FK；几何残差经 G1 冗余臂 IK 转成关节增量。若 IK 不可靠则退回 `ee`，但需用观测关节状态跟踪实际构型并对扫掠体做保守包络。

**所需资源**：公开 32 数据集（离线标定位姿模型/阈值）、单张推理卡（策略 + 轻量位姿/深度）、G1 URDF。无需额外真机权限。

**落地步骤**：① 建立位姿管线与 `FK(q)↔EE` 自检；② 用数据集回放采集「安全距离分布」定 `ε`；③ 实现三层修复与相位门控伺服；④ 在 UIP-07 回放 harness + MuJoCo 代理上做消融；⑤ 接入 v1 wrapper；⑥ 提测。

**风险**：位姿误差 → 误报安全 / 误报碰撞；透明物体位姿漂移；IK 与评测器控制器不一致导致扫掠体预测偏差。

## 2. 关键算法（接口忠实的块级伪代码）

```python
import numpy as np
from se3 import log_SE3, inv_SE3, exp_SE3

class GACRPolicy:
    """wrapper：语义 VLA + 几何整流。返回整段 T_a 动作块。"""
    def __init__(self, vla, pose_est, kin, esdf, cfg):
        self.vla, self.pose, self.kin, self.esdf = vla, pose_est, kin, esdf
        self.cfg = cfg                      # T_a, eps, alpha, conf_thr, tau_ttc...
        self.token = cfg.token

    @property
    def metadata(self):
        return {
            "control_space": "joint",
            "obs_delta_indices": {
                "observation.language": [0],
                "observation.images.cam_left_high":  [0],
                "observation.images.cam_right_high": [0],
                "observation.images.cam_left_wrist": [0],
                "observation.images.cam_right_wrist":[0],
                "observation.state.left_arm":  [-4, -2, 0],
                "observation.state.right_arm": [-4, -2, 0],
                "observation.state.left_ee_pose_gripper_base":  [-4, -2, 0],
                "observation.state.right_ee_pose_gripper_base": [-4, -2, 0],
                "observation.state.left_gripper":  [-4, 0],
                "observation.state.right_gripper": [-4, 0],
            },
            "image_resize": {"observation.images.cam_left_high": [360, 480],
                             "observation.images.cam_right_high": [360, 480]},
            "action_chunk_size": cfg.T_a,   # k 步 = 反应延迟
            "token": self.token,
        }

    def reset(self):
        self.vla.reset()
        self.prev_chunk = None

    def get_action(self, obs):
        # 1) 块边界：同步、定迭代次数的几何信念（保证延迟低方差）
        B = self.pose.build(obs)                    # 物体位姿 + ESDF + 人手
        fk_err = self.kin.selfcheck(obs)            # FK(q) 与观测 EE 残差
        # 2) 语义策略先给块
        A = self.vla.get_action(obs)                # 双 7 维关节目标, shape (T_a,7)x2
        # 3) 几何整流（置信度门控）
        if B.conf >= self.cfg.conf_thr and fk_err <= self.cfg.fk_thr:
            A = self.rectify(A, obs, B)
        else:
            A = self.slow_only(A)                   # 退化：只减速、不改向
        # 4) 人机让行 + 一致性护栏
        A = self.yield_human(A, obs, B)
        A = self.smooth_guard(A, obs)
        return self.pack(A, obs)

    def rectify(self, A, obs, B):
        if self.clearance(A, obs, B) >= self.cfg.eps:
            return self.servo_blend(A, obs, B)      # 安全时只做接触前小残差
        # L1 时间缩放
        for lam in (0.6, 0.4, 0.25):
            A2 = time_scale(A, obs.q, lam)
            if self.clearance(A2, obs, B) >= self.cfg.eps:
                return self.servo_blend(A2, obs, B)
        # L2 插入 via-point：沿 ESDF 负梯度抬升/绕行
        A3 = insert_via_point(A, obs, B, eps=self.cfg.eps)
        if self.clearance(A3, obs, B) >= self.cfg.eps:
            return self.servo_blend(A3, obs, B)
        # L3 仍不安全：回撤本块，下一块重规划
        return self.retract_chunk(obs, B)

    def clearance(self, A, obs, B):
        qs = self.kin.interp(obs.q, A)              # 沿块插值
        links = [self.kin.fk(q) for q in qs]
        d_scene = self.esdf.min_signed_distance(links)
        d_self = self.kin.min_link_distance(links)
        return min(d_scene, d_self)

    def servo_blend(self, A, obs, B):
        if not B.near_contact():                    # 相位门控：运输段不干预
            return A
        Tg = B.target_pose(self.task, self.subgoal) # 抓取点/孔位/杯口
        Te = obs.ee_pose_of_active_arm
        xi = log_SE3(Tg @ inv_SE3(Te))
        dq = self.kin.ik_delta(xi * self.cfg.alpha)
        w = self.cfg.w_max * B.target_conf          # 低置信度自动降权
        return blend_joint(A, dq, ramp(w, self.cfg.T_a))

    def yield_human(self, A, obs, B):
        if not B.human:
            return A
        if self.ttc(A, obs, B.human) > self.cfg.tau_ttc:
            return A
        hold = self.hold_or_retreat(obs, B)         # 保持/回撤，保持位姿连续
        return smooth_transition(A, hold)

    def smooth_guard(self, A, obs):
        A = rate_limit(A, self.cfg.v_max, self.cfg.a_max)
        A = jerk_limit(A, self.cfg.j_max)
        return clip_joint_limits(A, self.kin.limits)
```

**三层修复的次序理由**：时间缩放代价最小且不改变几何意图；via-point 会改变路径但保持目标；方向投影 / 回撤代价最大，作为兜底。所有修复都在固定 `T_a` 内完成，确保接口形状不变。

## 3. 关键推导

### 3.1 为什么碰撞护盾对「步骤分」是左尾优化

令 `C = Σ_j s_j · 1[完成前缀 j]`，灾难事件集合 `K`（扫倒 / 互撞 / 撞坏）。则
`E[C] = P(¬K)·E[C|¬K] + P(K)·E[C|K]`，且通常 `E[C|K] ≪ E[C|¬K]`。
护盾不改变 `E[C|¬K]`，只降低 `P(K)`，于是
`ΔE[C] ≈ (E[C|¬K] − E[C|K])·ΔP(K)`。
**示意性数值（假设，需代理验证）**：若 `E[C|¬K]=45`、`E[C|K]=10`、`P(K)` 从 8% 降到 3%，则 `ΔE[C]≈0.05×35=1.75` 分；同时成功率的提升另计。这说明护盾的价值不必依赖「提高成功率」也能体现，符合排名口径。

### 3.2 人机 TTC 的闭式解

用手位姿估计速度 `v_h`、机器人末端预测速度 `v_r`，相对量 `r0 = x_r − h_t`、`v = v_r − v_h`，安全半径 `R = r_robot + r_human`。碰撞条件 `‖r0 + v s‖² ≤ R²`：
`a=‖v‖², b=2 r0·v, c=‖r0‖²−R²`，
若 `b²−4ac ≥ 0`，最早碰撞时间
`s* = (−b − √(b²−4ac)) / (2a)`（取最小正根）。
若 `s* < τ_yield` 则让行。反应延迟上界为 `T_a·Δt`；30fps、`T_a=8` 时约 267ms，`T_a=4` 时约 133ms，这是**可调的安全-效率旋钮**。

### 3.3 位姿不确定性进入安全裕度

设物体位姿误差协方差 `Σ_i`，取主方向标准差 `σ_max`。保守安全裕度
`ε_eff = ε_base + k·σ_max, k=2`。
这把「位姿可能错」显式转成「要求更大的间距」，避免假安全；反向的假碰撞由置信度门控 + 退化到只减速来缓解。

### 3.4 ESDF 一阶安全投影

若某 waypoint `x` 处 `sd(x)<ε`，最近障碍点为 `x*`，法向 `n=∇sd(x)/‖∇sd(x)‖`，则一阶修正
`Δx = (ε − sd(x))·n`。
把修正加到 via-point 后重新做最小 jerk 插值。该投影不保证全局最优，但单次 O(1) ESDF 查询即可，适合块级实时预算。

### 3.5 延迟预算（每次 `get_action`，`T_a=8`）

| 阶段 | 预计耗时 | 频率 | 备注 |
|---|---|---|---|
| 立体深度 / 修正 | 6–12 ms | 每块 | 固定分辨率 |
| 多视图物体位姿（定迭代 ICP/热力图） | 20–35 ms | 每块 | 禁用自适应迭代以稳方差 |
| FK + 扫掠体 + ESDF 查询 | 3–6 ms | 每块 | `T_a` 个 waypoint |
| 相对位姿伺服 / 修复 | 1–3 ms | 每块 | 解析式 |
| 合计新增 | ≈ 30–55 ms | 每块 | 目标 std < 10 ms |

由于 `T_a=8`、30fps 下块周期约 267ms，新增开销约占 12–20%，但**低方差**；这比「偶尔一次 300ms 的异步重算」更符合 §6 的可信度口径。

## 5. 其余点（结构化）

**UIP-12 GPV**｜机制：把子目标写成 6D 位姿的确定性谓词（套叠/插入深度/直立/归位），输出 `done/fail/ongoing`。差异：比 VLM 快、可解释、可微调阈值；VLM 仅兜底语义歧义。可行性：高。步骤：谓词库→数据集回放标注→阈值标定→接入 v1 重试。风险：谓词覆盖不足导致误判。

**UIP-13 TTC-Yield**｜机制：堆叠帧估人手速度→TTC→让行块。差异：显式针对「人为干扰」轴，且用平滑保持而非急停。可行性：中高（人手检测 + 跟踪）。步骤：检测→TTC→让行/恢复→平滑过渡。风险：误检导致频繁停顿。

**UIP-14 TPA**｜机制：用桌面平面拟合建立重力/米制基准，用机械臂自身在相机中的 FK 投影做外参自标定；每台机器独立。差异：不依赖比赛方给的内外参，抗背景与机位差异。可行性：高。步骤：平面拟合→臂自观察→外参优化→在线校验。风险：桌面无纹理时平面拟合不稳。

**UIP-15 AGD**｜机制：从部分点云 + 可供性热图枚举候选接近方向，用扫掠体检查选无碰撞者。差异：把抓取方向选择显式化为几何搜索。可行性：中高。步骤：候选生成→碰撞打分→择优。风险：候选空间不足导致漏掉可行方向。

**UIP-16 SLIP-MON**｜机制：跟踪夹爪与物体的相对位姿；漂移超阈判滑移，触发重抓。差异：在拖动前就发现失败。可行性：高（腕部近景）。步骤：相对位姿→漂移检测→重抓策略。风险：透明物体跟踪丢失造成误报。

**UIP-17 MVF**｜机制：高位双目 + 双腕的多视图位姿融合与一致性过滤。差异：专攻透明/遮挡/低分辨率。可行性：中（透明物体仍是难点）。步骤：单视图位姿→位姿图融合→置信度输出。风险：多视图都失败时无解。

**UIP-18 CAS**｜机制：块内限速/限加速度/限 jerk、关节限位裁剪、离群点替换。差异：直接对齐 §6 的动作统计规律性。可行性：高。步骤：约束实现→回放验证→阈值。风险：过度平滑削弱策略灵敏度。

**UIP-19 GeoAug**｜机制：用估计位姿做物体替换/位姿扰动/相机扰动增广，并对齐不同机器的坐标。差异：几何轴对齐而非像素增广。可行性：中高（需离线位姿）。步骤：位姿标注→增广→消融。风险：增广分布偏离真机。

**UIP-20 GEO-ARB**｜机制：按 `B_t` 置信度、FK 残差、接触阶段在「原语义块 / 几何校正块 / 回撤块」间仲裁。差异：把仲裁显式化，避免几何层喧宾夺主。可行性：高。步骤：门控变量→仲裁规则→平滑切换。风险：门控抖动导致行为跳变。

## 7. 本轮最大风险（承接想法区 §6）

**一句话**：位姿 / 标定 / FK 的系统偏差会让护盾「误伤」本来可行的动作，因此 GACR 必须先通过 `(q_t, ee 位姿)` 在线自检与置信度门控把「几何层是否可信」变成可观测判据，并保留「只减速不改向」的安全退化路径，否则它会把一个失败模式换成另一个失败模式。
