### 第 5 轮灵感驱动研究记录（继承 v4；本轮为新一轮循环第 1 轮）

**灵感词**：云边协同、轨迹优化

**继承关系**：第 4 轮 CADVS-v4（IP-489~492）在 v3 五锚点（空间锚 3DCF、物理锚 MSRG、人因锚 HICK、末点锚 EEK、记忆锚 LTEM）与联邦锚 FFA 之上，追加价值锚 VACK（kc_val）与平衡锚 BCK（kc_bal），形成七硬门 kc_evidence_forged_v4 = kc_coverage ∧ kc_physics ∧ kc_human ∧ kc_ee ∧ kc_mem ∧ kc_val ∧ kc_bal，fail-closed；软评分 ECS_v4 = ECS_v3 · η_val · η_bal；执行集 Exec_CADVS-v4 ⊆ Exec_CADVS-v3 ⊆ Exec_CADVS-v2 ⊆ Exec_CADVS-v1 ⊆ Exec_v29。v4 已把「最大风险」明确定位为**重证书的计算开销挤爆 1 kHz 控制环**。本轮不推翻 v4，而是从「证书放在哪算」（云边协同）与「证书如何主动构造轨迹」（轨迹优化）两个方向补强，形成 CADVS-v5（IP-493~496），执行集嵌套升级为 Exec_CADVS-v5 ⊆ Exec_CADVS-v4 ⊆ … ⊆ Exec_v29（严格性有条件，见定理 5）。

**直觉与动机**：

1. **云边协同：把证书放到「该算的地方」，从算法压缩转向计算分层**。v4 试图把 VACK（~10–50 ms）与 BCK（~1–5 ms）压进 1 ms 控制环，继续压缩会遇到物理下限。更根本的解法是按「时间尺度 × 数据规模 × 全局性」分层：**云端**负责慢、大、全局——偏好模型推理、联邦先验、长时域轨迹优化、证书模型检查与离线验证；**边缘**负责快、小、局部——EEK、BCK 近似、短时域轨迹精化、证书缓存与轻量复核；**控制层**只做 O(1) 的门查询与摘要校验。证书因此从「一个布尔值」升级为「带有效性契约的分布式对象」V = (t_issued, Δ, model_version, digest)：谁算的、何时算的、用哪个模型版本、多久内有效、边缘能否用摘要本地复核。这暴露出 v4 未建模的两个新失效模式——**陈旧（stale）**与**版本漂移（version drift）**——必须显式上升为硬门，而不是默认证书永远新鲜。

2. **轨迹优化：把轨迹从「被评估的输入」变成「被优化的决策变量」，证书从「过滤器」变成「约束 + 构造器」**。v4 的硬门是「给定轨迹 → 判真伪」，门失败时只能停机或找教师。v5 定义证书约束轨迹优化 CCTO：min J(ξ) s.t. 所有 kc_i(ξ) 成立，返回可行见证 ξ* 与（若不可行）对偶 / Farkas 不可行证书。三个收益：(a) 门失败时在认证可行域内重优化出最近可行轨迹（projected fallback），把「否决」变「修复」；(b) 证书通过 = 存在可被独立验证的见证，CCTO 成为 certifying algorithm，优化者与验证者分离；(c) 云边天然分工——云端长时域全局轨迹 + 鲁棒正不变管（tube），边缘短时域在 tube 内精化并输出 tube 成员证书。

3. **二者相乘：分层可执行证书（hierarchical executable certificate）**。证书 = 三元组 (可行集 F, 见证 ξ*, 有效性契约 V)；执行集 = {轨迹 : 存在有效见证}。这同时缓解 v4 的实时性硬伤（重计算上云、边缘只做轻量复核与短时域优化），又把「被动否决」升级为「主动构造」。但必须诚实：可行性证书依赖优化器，非凸 + 数值容差会产生「伪见证」与「不可判定」两个新缝隙，前者是安全漏洞，后者是可用性代价。

**关键洞见**：v4 七锚点回答「证据是否齐全」；v5 第八锚（轨迹锚 kc_traj）回答「是否存在一条可执行、可独立验证、未过期的见证轨迹」，kc_fresh 把「证据的时间有效性」纳入硬门，kc_tube 把「云边参考一致性」纳入硬门。九硬门 kc_evidence_forged_v5 = kc_coverage ∧ kc_physics ∧ kc_human ∧ kc_ee ∧ kc_mem ∧ kc_val ∧ kc_bal ∧ kc_traj ∧ kc_fresh（存在云端参考时再加 kc_tube），fail-closed；软评分 ECS_v5 = ECS_v4 · η_traj · η_fresh。退化阶梯 full → edge_only → static_safe 保证分区时执行集退回 v4 而绝不放大。

**形式化目标（增量）**：
1. 定义分层分配 π: {kc_i} → {cloud, edge, control} 与有效性契约 V_i = (t_i, Δ_i, model_version, digest)；硬门 kc_fresh = (t − t_i ≤ Δ_i) ∧ version_match ∧ digest_match；软因子 η_fresh = max(0, 1 − (t − t_i)/Δ_i)。
2. 定义 CCTO 与轨迹证书 TOC = (feasible, ξ*, J*, binding_gates, proof, t, model_version)；kc_traj = (TOC.feasible ∧ proof 独立复核通过 ∧ 执行轨迹 ∈ Tube(ξ*))；软因子 η_traj = clip((J_max − J*)/J_max, 0, 1)。
3. 定义 HCETO：云端输出长时域参考 ξ^ref 与鲁棒正不变 tube，边缘在 tube 内以 ξ^ref 为热启动做短时域 CCTO；kc_tube = (ξ_exec ∈ Tube(ξ^ref))。
4. 定义条件单调收缩定理：无分区时 Exec_v5 ⊆ Exec_v4 且严格；分区时退化到 Exec_v4，故任意时刻执行集都不超出 v4。
5. 定义延迟–新鲜度可行性：给定云 RTT 分布与边缘计算预算，存在分层分配使 P(stale) ≤ ε 当且仅当 Δ ≥ F_RTT^{-1}(1−ε) 且门代价背包可行。
6. 定义 EFA-v5 九硬门 + ECS_v5 = ECS_v4 · η_traj · η_fresh。
7. 定义退化阶梯 full → edge_only → static_safe，并证明每一级执行集都不超出上一轮 v4 认证集。

**本轮最大风险**：**「伪见证」**——非凸轨迹优化、数值容差与模型失配下，CCTO 可能声称存在可行见证而实际执行轨迹违反硬门；云边分层又把验证责任分散到两端，使这种「看似有证、实则失效」的隐性失效更难在线发现。

## 2. 关键算法骨架

### IP-493 CECB：云边证书总线（分层分配 + 有效性契约 + 退化）

```python
@dataclass
class ValidityContract:
    tier: str            # 'cloud' | 'edge' | 'control'
    t_issued: float
    horizon: float       # Δ_i：有效期（秒）
    model_version: str
    digest: str          # h(x, context, model_version) 的哈希摘要

@dataclass
class CloudEdgeCertificateBus:
    """CECB：把证书放到该算的地方；用有效性契约把「分布式」变成可验证的硬门"""
    control_period: float = 0.001
    edge_budget_ms: float = 0.85       # 每周期边缘证书预算（留 0.15 ms 给控制）
    stale_eps: float = 1e-3            # 允许的陈旧概率
    local_model_version: str = "v5.0"

    def assign(self, gates: dict[str, GateCost], budget_ms: float) -> dict[str, str]:
        """0-1 背包/ILP：最小化最坏延迟，s.t. Σ_{i∈edge} c_i ≤ budget_ms
           且每个云门满足 P(age > Δ_i) ≤ ε_stale。输出 π。"""
        # 约束1：边缘预算；约束2：云 RTT 分位数 Δ_i ≥ F_RTT^{-1}(1−ε_stale)
        # 目标：min max_i latency_i(π(i))，同延迟取成本最低层
        ...

    def accept(self, cert: ValidityContract, x, context, t_now) -> tuple[bool, str]:
        """kc_fresh 的实现：O(1) 摘要 + 版本 + 年龄校验"""
        if t_now - cert.t_issued > cert.horizon:            return False, 'STALE'
        if cert.model_version != self.local_model_version:  return False, 'VERSION_DRIFT'
        if cert.digest != digest(x, context):               return False, 'CONTEXT_CHANGED'
        return True, 'FRESH'

    def eta_fresh(self, cert, t_now) -> float:
        return max(0.0, 1.0 - (t_now - cert.t_issued) / cert.horizon)

    def degrade(self, cloud_alive: bool, oldest_age: float) -> str:
        """退化阶梯：分区/过旧时退回 v4 已认证的本地证书集，绝不放大执行集"""
        if cloud_alive and oldest_age <= self.max_cloud_age(): return 'full'
        if cloud_alive:                                        return 'edge_only'
        return 'static_safe'   # 仅 EEK+BCK 本地门，等价 v4 保护级别
```

### IP-494 CCTO：证书约束轨迹优化（边缘短时域 / 云端长时域，certifying algorithm）

```python
@dataclass
class TrajectoryCertificate:
    feasible: bool
    xi: Optional[Trajectory]          # 可行见证
    J: float
    binding: tuple[str, ...]          # 活跃约束（哪几个门在边界上）
    proof: Any                        # 可行=独立复核轨迹；不可行=Farkas/对偶证书
    t: float
    model_version: str

@dataclass
class CertifyingTrajectoryOptimizer:
    """CCTO：min J(ξ) s.t. 所有 kc_i(ξ)；返回见证或不可行证书"""
    horizon: int = 16
    max_iter: int = 40
    tol_opt: float = 1e-3             # 优化容差
    tol_verify: float = 1e-4          # 验证容差更严 → ε_gap > 0，杜绝伪见证
    gates: list[Callable] = field(default_factory=list)

    def solve(self, x0, context, t_now, warm_start=None) -> TrajectoryCertificate:
        xi = warm_start if warm_start is not None else self._init(x0)
        for _ in range(self.max_iter):
            xi = self._constrained_step(xi, context)          # SQP / iLQR + 增广拉格朗日
            if not self._converged(xi):                        continue
            if not self._gates_pass(xi, context, t_now):       continue
            proof = self._verify_independently(xi, context)    # 验证者与优化者分离
            if proof.ok and self._tube_contains(proof.tube, xi):
                return TrajectoryCertificate(True, xi, self._cost(xi),
                                             self._active(xi), proof, t_now, self.v)
        dual = self._infeasibility_certificate(xi)             # 对偶 / Farkas
        return TrajectoryCertificate(False, None, float('inf'), (), dual, t_now, self.v)

    def kc_traj(self, toc: TrajectoryCertificate, xi_exec) -> bool:
        """引理 44：通过 ⟹ 存在独立复核通过的见证且执行落在见证 tube 内"""
        return (toc.feasible and toc.proof.ok
                and self._tube_contains(toc.proof.tube, xi_exec))

    def _verify_independently(self, xi, ctx): ...   # 用更严格容差、独立模型副本复核
    def _infeasibility_certificate(self, xi): ...   # 非凸时可能返回 inconclusive
```

### IP-495 HCETO：云边分层轨迹优化（云端参考 + RPI tube + 边缘精化）

```python
@dataclass
class HierarchicalCloudEdgeTO:
    cloud_horizon: int = 100
    cloud_dt: float = 0.05
    edge_horizon: int = 16
    edge_dt: float = 0.001

    def cloud_solve(self, x0, global_context) -> tuple[Trajectory, Tube]:
        """云端：慢、长时域、含全局价值/平衡先验；输出参考与鲁棒正不变管"""
        xi_ref = self._long_horizon_opt(x0, global_context)
        tube = self._rpi_tube(xi_ref, disturbance_bound=self.w_bound)
        return xi_ref, tube

    def edge_refine(self, x0, xi_ref, tube, context, t_now) -> TrajectoryCertificate:
        """边缘：以 xi_ref 热启动，在 tube 内做短时域证书约束优化"""
        toc = self.ccto.solve(x0, context, t_now, warm_start=xi_ref)
        if toc.feasible and not self._tube_contains(tube, toc.xi):
            # 见证越出云端 tube：降级为 tube 内投影，或请求云端重规划
            toc = self.ccto.solve(x0, context, t_now,
                                  warm_start=self._project_into(tube, xi_ref))
        return toc

    def kc_tube(self, tube, xi_exec) -> bool:
        """引理 45：通过 ⟹ 执行轨迹在鲁棒正不变管内，偏差有界"""
        return self._tube_contains(tube, xi_exec)
```

### IP-496 EFA-v5：九硬门 + 软评分 + 证据铸造流水线 v5

```python
@dataclass
class EvidenceForgingAssemblerV5:
    """EFA-v5：九硬门 fail-closed；软评分 ECS_v5 = ECS_v4 · η_traj · η_fresh"""
    scf: SpatialCoverageFieldKernel
    msrg_cache: dict
    hic: HumanIntentCertificateKernel
    eek: EndEffectorFidelityKernel
    ltem: LongTermEpisodicMemory
    vack: ValueAlignmentCertificateKernel
    bck: BalanceControlKernel
    cecb: CloudEdgeCertificateBus
    ccto: CertifyingTrajectoryOptimizer
    hceto: HierarchicalCloudEdgeTO
    mu_S: float = 0.75
    w: tuple = (0.4, 0.4, 0.2)

    def hard_gate_v5(self, x, t_now, rule_id, hic, eec: EEC, bcc: BCC,
                     traj: Trajectory, context: Context,
                     certs: dict[str, ValidityContract],
                     toc: TrajectoryCertificate, tube=None) -> tuple[bool, str]:
        # 0) 最高优先级人因否决
        if self.hic.veto_active(hic):                 return False, 'HIC_STOP'
        # 1) 新鲜度元门：任何来自云/缓存的证书先验有效性（防止陈旧/漂移）
        for name, cert in certs.items():
            ok, why = self.cecb.accept(cert, x, context, t_now)
            if not ok:                                return False, f'CERT_{name}_{why}'
        # 2) v4 原有七门
        if not self.scf.kc_coverage(x, t_now):        return False, 'COVERAGE_BLIND'
        s2rc = self.msrg_cache.get(rule_id)
        if s2rc is None or s2rc.verdict != 'accept' or s2rc.mu_pass < self.mu_S:
            return False, 'PHYSICS_UNPROVEN'
        if not self.eek.kc_ee(eec):                   return False, 'EE_UNPROVEN'
        if not self.bck.kc_bal(bcc):                  return False, 'BALANCE_UNSTABLE'
        pass_mem, _, novelty = self.ltem.query(context.obj, context.geo,
                                               context.theta_fp, rule_id)
        if not pass_mem:                              return False, 'MEMORY_REJECT'
        vac = self.vack.evaluate(traj, context, t_now)
        if not self.vack.kc_val(vac):                 return False, 'VALUE_MISALIGNED'
        # 3) 轨迹锚：存在可独立复核的见证
        if not self.ccto.kc_traj(toc, traj):          return False, 'TRAJ_UNWITNESSED'
        # 4) 云边一致性（有云端参考时）
        if tube is not None and not self.hceto.kc_tube(tube, traj):
            return False, 'TUBE_ESCAPE'
        return True, 'FORGED_V5' + ('|NOVELTY' if novelty else '')

    def ecs_v5(self, x, t_now, rule_id, A_att=0.0, eta_mem=0.5, eta_val=0.5,
               eta_bal=0.5, eta_traj=0.5, eta_fresh=0.5) -> float:
        base = (self.scf.gamma3d(x, t_now)**self.w[0]
                * getattr(self.msrg_cache.get(rule_id), 'mu_pass', 0.0)**self.w[1]
                * (1 + self.w[2]*A_att))
        return base * eta_mem * eta_val * eta_bal * eta_traj * eta_fresh
```

### 集成流水线与云边时序

```
云端（慢时域，10–20 Hz / 事件触发）：
  FFA 全局先验 + VACK 完整偏好推理 + CERTCALC 模型检查
    ──▶ HCETO.cloud_solve：长时域参考 ξ^ref + RPI tube + 价值/平衡先验
    ──▶ 签发带有效性契约的证书 V=(t,Δ,v,digest) ──▶ 下发（~几 KB，10–20 Hz）

边缘（快时域，1 kHz 控制 + 100–200 Hz 精化）：
  kc_fresh 校验云证书（O(1)：年龄/版本/摘要）
    ├─ FRESH      → 使用云端先验，CCTO.edge_refine 在 tube 内短时域优化
    ├─ STALE      → 丢弃云证书，走 edge_only（v4 本地证书）
    └─ VERSION_DRIFT / CONTEXT_CHANGED → 请求云端重签发，本地降级
  每周期：EEK→EEC→kc_ee；BCK(近似)→BCC→kc_bal；CCTO 读缓存 TOC→kc_traj
  证书消费前：EFA-v5.hard_gate_v5(...)
      ├─ CERT_*_STALE / *_VERSION_DRIFT → 退化阶梯，必要时 S_stop
      ├─ BALANCE_UNSTABLE               → 阻抗软化 / 回退姿态
      ├─ TRAJ_UNWITNESSED               → 在 F_t 内 projected fallback；仍不可行则 S_stop
      └─ TUBE_ESCAPE                    → 投影回 tube / 请求云端重规划
  控制层（1 kHz）：只做 O(1) 门查询与摘要校验，不做重优化

退化阶梯：
  full（云+边） ──分区/过旧──▶ edge_only（=v4 本地认证集） ──本地也不可信──▶ static_safe
  单调性：每一级执行集都不超出 v4，故任意时刻 Exec_v5(t) ⊆ Exec_v4。
```

**通信开销**：
- 云→边：参考轨迹 ξ^ref + tube + 证书，~2–8 KB/次，10–20 Hz ⇒ ~40–160 KB/s；可压缩到关键点 + 协方差。
- 边→云：聚合状态/摘要/不可行统计，~1–5 KB/s（不做 1 kHz 原始流上传）。
- 隐私：原始感知与偏好数据不离边；云端仅见摘要与统计量；DP 由 FFA 继续保证。

**实时性缓解（相对 v4 的实质改进）**：
- 重证书上云：VACK 完整推理、CERTCALC 模型检查、长时域 CCTO 不再进入控制环。
- 边缘只做短时域 CCTO（H_e=16，温启动 + 早停），并把 BCK 精确 QP 换成云标定查表 + 在线插值。
- 控制层只做 O(1) 门查询；`kc_fresh` 摘要校验可用硬件哈希。

## 4. 正确性论证（增量更新）

### 引理 43（新鲜度—陈旧健全性）

**陈述**：设证书性质 kc_i 关于上下文/状态是 L-Lipschitz 的，状态漂移满足 ‖x(t) − x(t_i)‖ ≤ ρ·(t − t_i)，模型版本差异 ‖v − v_local‖ ≤ δ_v。若 kc_fresh 通过（age ≤ Δ、版本匹配、摘要匹配），则证书在 t 时刻的性质边际至少下降 L(ρΔ + δ_v)。

**证明**：由 Lipschitz 性与漂移界，|kc_i(x(t)) − kc_i(x(t_i))| ≤ L‖x(t) − x(t_i)‖ ≤ LρΔ；版本差异再贡献 Lδ_v；摘要匹配排除了上下文跳变。故只要原始边际 > τ_i + L(ρΔ + δ_v)，通过仍健全。∎

**工程含义**：Δ_i 不能拍脑袋，应由 `Δ_i ≤ (margin_i − τ_i)/(Lρ)` 反推；这正是 CECB.assign 的约束之一。

### 引理 44（CCTO 见证健全性 / certifying algorithm）

**陈述**：若 CCTO 返回 feasible 且独立验证者以 tol_verify < tol_opt 复核通过，则执行 ξ* 满足全部硬门；若返回带合法 Farkas 证书的 infeasible，则 F_t = ∅。若两者皆无（非凸不可判定），必须 fail-closed。

**证明**：验证者使用更严格容差，故 `tol_opt` 下的近似可行在 `tol_verify` 下被拒，杜绝「优化器自证」的伪见证（认证间隙 ε_gap > 0）。Farkas 证书是线性化系统不可行的对偶见证，成立则无可行点。非凸情形优化器可能既找不到见证也证不出不可行，此时按定义 kc_traj = ⊥。∎

**工程含义**：把「优化」与「验证」在代码、模型副本、容差上彻底分离；不可判定比例作为可用性指标单独监控。

### 引理 45（分层 tube 安全性）

**陈述**：若云端 tube 对扰动界 w 鲁棒正不变（RPI），且边缘执行轨迹满足 kc_tube，则即使存在 ≤ w 的模型失配，边缘状态始终留在 tube 内，且与参考 ξ^ref 的偏差有界。

**证明**：RPI 定义给出 x_t ∈ Tube ⇒ x_{t+1} ∈ Tube（对任意 ‖d‖≤w）；kc_tube 保证入口在管内，归纳即得。偏差界由 tube 半径给出。∎

### 定理 5（条件单调信任收缩）

**陈述**：
(i) 无分区且证书新鲜时，Exec_v5 ⊆ Exec_v4，且若存在 v4 接受但无见证的轨迹则严格 ⊂。
(ii) 分区/陈旧时，退化阶梯把执行集置为 Exec_v4（edge_only）或更小的 static_safe，故仍 ⊆ Exec_v4。
(iii) 因此 ∀t，Exec_CADVS-v5(t) ⊆ Exec_CADVS-v4；在完整链路可用时严格 ⊆。

**证明**：v5 的所有新增门（kc_fresh、kc_traj、kc_tube）都是合取项，只会缩小执行集；退化阶梯显式定义为「回到 v4 的本地认证集」，不引入 v4 之外的轨迹。严格性由「无见证轨迹」非空保证。∎

**诚实说明**：这是「设计级」条件收缩，不是无条件收缩——若实现中退化路径偷偷放宽了 v4 的某个门，则定理失效。因此退化阶梯必须复用 v4 的同一份门实现，并有契约测试。

### 定理 6（延迟—新鲜度可行性）

**陈述**：给定云 RTT 分布 F_RTT、陈旧概率上界 ε_stale、边缘每周期预算 B_e、各门边缘代价 c_i，存在分层分配 π 使 P(stale) ≤ ε_stale 且 Σ_{i:π(i)=edge} c_i ≤ B_e，当且仅当 Δ ≥ F_RTT^{-1}(1−ε_stale) 且对应 0-1 背包可行。

**证明**：P(stale) = P(RTT > Δ) = 1 − F_RTT(Δ) ≤ ε_stale ⇔ Δ ≥ F_RTT^{-1}(1−ε_stale)；边缘延迟约束是标准 0-1 背包可行性。两者独立，故取合取。∎

**工程含义**：把「云边怎么切」从经验变成可求解的可行性问题；若不可行，唯一诚实的选择是降低 ε_stale 或提高 B_e（硬件），而不是假装证书新鲜。

### 定理 7（轨迹锚的构造性完备）

**陈述**：在 v4 七锚点假设 (B1)~(B5) 与引理 44 下，v5 的证据链对「执行」是构造性完备的：每个控制周期要么输出可执行且可验证的见证，要么 fail-closed。八锚点 {3DCF, MSRG, HICK, EEK, LTEM, VACK, BCK, CCTO} 缺一不可（去轨迹锚则失去「存在性见证」，退回 v4 的被动过滤）。

**证明**：由 CCTO 的穷举分支（feasible-witness / infeasible-certificate / inconclusive→⊥）与 v4 定理 4 的七锚完备性直接合成。反例：v4 可通过一条「所有静态门都过、但轨迹规划不可行」的规则，v5 因 kc_traj 拒绝。∎

## 5. 实验设计与初步结果（仿真，第 5 轮）

### 5.1 实验设计

- **平台**：云端节点（GPU）+ 边缘 Jetson Orin + Panda 舰队（N=3~5）+ 网络仿真器（tc/netem：5G 20–50 ms、WiFi 5–15 ms、分区 100% 丢包、抖动 ±30 ms）。

- **协议**：
  (a) 网络分区/抖动/版本漂移注入：测陈旧接受率、退化触发率、任务成功率；

- **指标**：认证执行率、fallback 恢复率（相对安全停机）、伪见证率、不可判定率、陈旧接受率、tube 逃逸率、控制延迟 P99/P99.9、丢帧率、任务成功率、ECS_v5 与失败 AUC、云边带宽。

## 7. 本轮最大风险（最终确认）

**一句话**：**「伪见证」**——非凸轨迹优化、数值容差与模型失配下，CCTO 可能声称存在可行见证而实际执行轨迹违反硬门；云边分层又把验证责任分散到两端，使这种「看似有证、实则失效」的隐性失效更难在线发现。
