# 第 67 轮（承接第 66 轮「RAS 情绪驱动闭环」IP-224~233；新灵感循环第 1 轮；本轮灵感：「续航能力」×「机器人操作系统」）

> 前 66 轮已经走完一条很清晰的递进：第 65 轮 VISTA 把闭环从「先验可证伪」推进到**故障可归因**（哪一层坏了）；第 66 轮 RAS 把「被动故障响应」推进到**意图可协商**（谁该控制、控制多少）。但这两代共享两个未被审视的默认假设：**能量是免费的**，**计算是瞬时的、单体的**。
>
> 本轮的两个灵感词恰好从两侧击穿这两个假设：
> - 「续航能力」：能量不是电量条，而是**维持安全承诺的时间预算**；
> - 「机器人操作系统」：安全不是单体模型的属性，而是**分布式运行时（节点/话题/QoS/executor/回调）涌现出来的属性**。
>
> 本轮核心命题：
>
> **把「故障可归因 + 意图可协商」的闭环，升级为「能量可持续 + 运行时可实现」的闭环：STAMINA（Safety-Time-Aware Mission-Intent Negotiation Architecture，续航感知的安全闭环）。**
>
> STAMINA 问的不再是「谁在控制、控制多少」，而是「**还能控制多久，以及这套控制本身能否按能量预算、按 deadline 被操作系统真正调度出来**」。

## 0. 直觉与动机

**灵感 1（续航能力 → 能量是一等安全约束，而非电量百分比）**
直觉：续航在工程上常被写成 `battery_level ∈ [0,1]`，但这对安全闭环毫无意义——80% 电量也可能因为任务太远而无法返航，20% 电量也可能足够安全停机。正确的语义是：**在剩余能量 `E_t` 下，系统还能维持既定安全承诺多久**。这与前几轮的 certified prefix 构成一个漂亮的对偶：VISTA/RAS 在**动作空间**上截断认证前缀 `k*`；STAMINA 在**能量空间**上截断认证前缀 `e*`——只有当「执行前缀 + 之后回到安全态」的能耗仍小于可用能量时，`e` 才可认证。于是「续航」从显示问题变成**可达性/不变式问题**。

**灵感 2（机器人操作系统 → 安全保证是分布式运行时涌现的）**
直觉：ROS 2 的节点、话题、QoS（reliability / deadline / liveliness / history depth）、executor 与回调组，意味着 VISTA 的「故障」未必是算法坏了，也可能是：safety 话题错过 deadline、TF 树某一帧过期、关键回调被感知节点挤占、消息队列丢帧。**安全的敌人从「模型误差」扩展到「调度与消息传递」**。这让此前所有「先算对再执行」的静态证书都必须补一条：**这份证书在运行时真的能被按时兑现吗？**

**灵感 3（续航 × ROS → 监测悖论：安全机器吃掉了安全预算）**
直觉：安全监测器（面部情绪识别、贝叶斯故障归因、认证前缀搜索）本身就是计算负载，是要吃电的。低电量时最直觉的省电做法是「关掉一些监测器」，但被关掉的往往正是捕获故障的那一个。于是：**保护安全的机器，会消耗它正在保护的那份能量**。这是本轮的核心张力，也是一个非单调问题——监测强度 `m` 太低不安全，太高则因耗电而增大「滞留危险态（stranding）」风险，因此必然存在内点最优 `m*`（见定理 12）。

**灵感 4（三灵感合流 → STAMINA 的六层结构）**
沿用 VISTA/RAS 的时序骨架，换装为：
1. **EOL Energy-OS Ledger**：带漂移不确定性的能量账本 + 每个 ROS 节点的功率剖面；
2. **RASP Risk-Adaptive Scheduling Protocol**：按「单位能量降低的风险」给 safety 节点排优先级，防优先级反转；
3. **ECP Energy-Certified Prefix**：算能量前缀 `e*`，与 `k_VISTA`、`k_emotion` 求交；
4. **MIN Mission-Intent Negotiation**：用 RAS 的意图/情绪后验收缩或扩张任务域，做「续航合同」协商；
5. **CCS Coupled-Collapse Shield**：强制保底调度 top-1 风险监测器 + fallback 监测器，否则立即回落；
6. **J_stamina Certificate**：在 `J_ras` 上追加能量账本、调度证明、任务域与「拒绝执行」标志。

**灵感 5（与前几代的谱系定位）**
- VISTA：**故障可归因**（哪一层坏了）；
- RAS：**意图可协商**（谁该控制、控制多少）；
- STAMINA：**能量可持续 + 运行时可实现**（还能控制多久、保证能否被兑现）。

## 1. 形式化定义（增量：定义 251–264）

- **定义 251（ROS 2 计算图与能量）**：`G_t = (N, T, Q, S)`，节点 `n∈N` 带 `(C_n 最坏执行时间, p_n 周期, d_n deadline, P_n 功率)`；话题 `T` 带 QoS；executor 集合 `S`。计算能耗 `E_comp(H) = Σ_n (C_n/p_n)·P_n·H`，总功率 `P = P_base + Σ_n u_n P_n + P_act`。
- **定义 252（能量账本）**：剩余能量估计 `Ê_t` 与不确定度 `±ε_E(t)`（温度、老化、内阻漂移），预留 `E_reserve`。**可用能量** `E_avail(t) = Ê_t − ε_E(t) − E_reserve`。
- **定义 253（安全回退能量）**：安全集 `S_safe`，`E_fb(x) = min_{s∈S_safe} cost(π_fb: x→s)`；回退可行 ⇔ `E_avail ≥ E_fb(x)`。
- **定义 254（能量认证前缀）**：对动作块 `A=(a_1..a_m)`，`e*(A) = max{ e : cost(A[:e]) + E_fb(x_{t+e}) ≤ E_avail(t) }`。
- **定义 255（联合认证前缀）**：`k*_ST = min(k_VISTA, k_emotion, e*)`；可行域 `Ω = {(k,e) : k ≤ e, k ≤ k_VISTA, k ≤ k_emotion}`。
- **定义 256（风险-能量优先级）**：监测器 `n` 的边际效率 `μ_n = ΔRisk_n / E_n`，调度按 `μ_n` 降序（在 deadline 与能量约束下做背包式分配）。
- **定义 257（监测悖论）**：监测强度 `m∈[0,1]`；安全损失 `L_s(m)=a·e^{−λm}`（随 m 降），滞留损失 `L_e(m)=b·m/E_avail`（随 m 升）；总损失 `L(m)=L_s(m)+L_e(m)`。
- **定义 258（任务域与意图）**：任务 `M=(goal, T_return, risk_cap)`；MIN 依据 RAS 的意图 `π` 与 `E_avail` 施加收缩算子 `M' = contract(M; π, E_avail)`。
- **定义 259（耦合崩塌）**：能量稀缺触发的调度降级，恰好关掉了捕获共发故障所需的监测器，导致「滞留危险态 ∧ 安全违规」同时发生的事件。
- **定义 260（耦合崩塌护盾 CCS）**：不变式：任何调度决策后，top-1 风险监测器与 fallback 监测器必须可调度；否则强制回落，不再继续任务。
- **定义 261（deadline 优先级继承）**：safety 话题消息继承其风险优先级，抑制 executor 中的优先级反转。
- **定义 262（J_stamina 证书）**：`J_stamina = (J_ras, E_avail, e*, schedule_attestation, M', refuse_flag)`；Valid ⇔ `Valid(J_ras) ∧ e* ≥ k*_ST ∧ 所有 top-risk 监测器满足 deadline ∧ E_avail ≥ E_fb`。
- **定义 263（续航合同）**：对人类的承诺「我将保留 `E_reserve`，并能在 `T_return` 内返航/停稳」；当合同不可满足时，MIN 必须显式协商或拒绝执行。
- **定义 264（降级阶梯）**：监测器按 `μ_n` 排序成阶梯，只在阶梯底部降级；降级不得改变 top-risk 假设的证书有效性。

## 2. 关键算法骨架

```python
# EOL：能量账本 + ROS 节点功率剖面
class EnergyOSLedger:
    def __init__(self, reserve, eps0=0.02):
        self.reserve, self.eps = reserve, eps0
    def update(self, measured, nodes, dt, thermal=1.0):
        # 带漂移的卡尔曼式估计
        self.hat = measured
        self.eps = min(0.15, self.eps + 0.001*dt) * thermal
        self.e_comp = sum(n.power * n.duty for n in nodes) * dt
        return self.available()
    def available(self):
        return max(0.0, self.hat - self.eps*self.hat - self.reserve)

# ECP：能量认证前缀
def energy_prefix(A, x0, e_avail, e_fb_fn, cost_fn):
    e_star, used, x = 0, 0.0, x0
    for i, a in enumerate(A):
        x = transition(x, a)
        used += cost_fn(a)
        if used + e_fb_fn(x) <= e_avail:
            e_star = i + 1
        else:
            break
    return e_star

# RASP：风险-能量优先级调度（背包式）
def risk_energy_schedule(monitors, energy_budget, deadlines):
    # μ_n = ΔRisk_n / E_n，按 μ 降序，在 deadline/能量约束下贪心+校验
    order = sorted(monitors, key=lambda n: n.delta_risk / n.energy, reverse=True)
    chosen, used = [], 0.0
    for n in order:
        if used + n.energy <= energy_budget and deadline_ok(n, deadlines):
            chosen.append(n); used += n.energy
    return chosen, used

# CCS：耦合崩塌护盾
def coupled_collapse_shield(chosen, top_risk, fallback_monitor):
    must = {top_risk.id, fallback_monitor.id}
    if not must.issubset({n.id for n in chosen}):
        return 'FORCE_FALLBACK'
    return 'CONTINUE'

# MIN：任务域协商（用 RAS 意图收缩）
def mission_intent_negotiate(M, pi_intent, e_avail, e_fb):
    margin = e_avail - e_fb
    if margin <= 0:
        return M.contract_to_safe()          # 只保留返航/停稳
    if pi_intent.risk > 0.6 or margin < 0.2*e_avail:
        return M.contract(scale=0.5)         # 主动缩小任务域
    return M

# STAMINA 闭环
def STAMINA_round(M, obs):
    V, T, P, L, P_cloud, W, tactile, img, depth, flow = obs
    # 0) 能量账本
    e_avail = M.eol.update(M.measured_energy, M.ros_nodes, M.dt)
    # 1) 原 VISTA/RAS 前向
    face_gate = M.er.gateway.recognize(img)
    A = M.vista.ach.propose(M.lsf.fuse(M.usr.fuse(V, T, P, L)), H=M.vista.H)
    rho = M.vista.fir.signature(M.vista.stage.split(M.vista.residual_log))
    joint_post, _ = M.efs.synthesize(rho, face_gate)
    # 2) 能量前缀 × 联合前缀
    e_star = energy_prefix(A, M.x, e_avail, M.e_fb, M.cost)
    k_safety = M.csc_ras.certified_prefix_ras(A, joint_post, M.m_ras, M.alpha_chunk)
    k_st = min(k_safety, e_star)
    # 3) 风险-能量调度 + 护盾
    chosen, used = risk_energy_schedule(M.monitors, e_avail - M.e_fb(M.x),
                                        M.deadlines)
    if coupled_collapse_shield(chosen, M.top_risk, M.fallback) == 'FORCE_FALLBACK':
        return M.fallback(e_avail), {'refuse': True, 'e_star': e_star}
    # 4) 任务域协商
    M.mission = mission_intent_negotiate(M.mission, M.intent_pi, e_avail, M.e_fb(M.x))
    # 5) 证书
    J = build_stamina_cert(M.j_ras, e_avail, e_star, k_st, chosen, M.mission)
    return M.dispatch(A[:k_st]), {'J': J, 'k_st': k_st, 'e_star': e_star,
                                  'sched': chosen, 'e_avail': e_avail}
```

## 3. 推导

**引理 11（回退可行性的单调性）** 若 `E_avail(t) ≥ E_fb(x_t)` 且动作 `a_t` 使系统更接近安全集，则 `E_avail(t+1) = E_avail(t) − cost(a_t) − E_comp(t) ≥ E_fb(x_{t+1})`。即「向安全集移动」的动作不会破坏回退可行性。

**引理 12（能量前缀存在性）** 若 `E_avail(t) ≥ E_fb(x_t) + c_min`（`c_min` 为单步最小动作能耗），则 `e* ≥ 1`；反之 `e* = 0`，系统必须直接回落而不执行任何任务动作。

**引理 13（护盾的局部无崩塌性）** 只要 top-1 风险监测器与 fallback 监测器可调度且其观测正确，CCS 触发 `FORCE_FALLBACK` 后系统不会进入耦合崩塌状态（定义 259）。

**定理 11（安全-能量联合证书）** 在 A92–A96（能量漂移有界 `|Ê−E|≤ε_E`、WCET 有界、监测器风险排序正确）下，受控系统满足
`P(strand ∨ safety_violation) ≤ δ_E + Σ_n P(deadline_miss_n) + α_chunk`，
且当 `schedule_attestation` 有效时 `J_stamina` 保持 Valid。

**定理 12（监测强度的内点最优）** 在定义 257 下，`L(m)` 严格凸，唯一最优
`m* = (1/λ)·ln(aλ·E_avail / b)`，
且 `∂m*/∂E_avail = 1/(λ·E_avail) > 0`——**可用能量越低，最优监测强度越低**。这不是「鼓励偷懒」，而是说明：能量稀缺时，过度监测本身会以更大代价推高滞留风险；CCS 负责把「低 m*」限制在不丧失 top-risk 覆盖的可行域内。

**定理 13（护盾无耦合崩塌）** 在 A92–A96 且 top-risk 监测器观测正确的前提下，CCS 不变式成立 ⇒ 任意能量水平下 `P(耦合崩塌)=0`。该定理把「省电降级」与「安全失效」解耦：可以降级，但不能降掉 top-risk。

## 6. 本轮最大风险

**一句话**：STAMINA 的全部定理都押在「能量模型可估且漂移有界、监测器的风险排序正确、且可以安全降级监测器」这三个前提上；一旦能量估计出现未建模漂移（温度/老化/负载突变）或降级顺序判错，调度器可能恰好关掉能捕获共发故障的那个监测器，制造「没电 + 不安全」的**耦合崩塌**——把原本可被 VISTA/RAS 降级的故障，变成一次同时失去能量与安全兜底的灾难性失败。

| `μ_n = ΔRisk_n / E_n` | 监测器单位能量风险降低（调度优先级） |
| `L_s(m)=a·e^{−λm}, L_e(m)=b·m/E_avail` | 安全损失、滞留损失 |
| `m* = (1/λ)·ln(aλ·E_avail/b)` | 最优监测强度（定理 12） |
| `M=(goal,T_return,risk_cap)` | 任务域；`contract(M;π,E_avail)` 为收缩算子 |
| `J_stamina` | 含能量账本、调度证明、任务域、拒绝标志的证书 |

## 2. 形式化定义（完整版）

**定义 251（ROS 2 计算图与能量）** 节点 `n∈N` 带 `(C_n, p_n, d_n, P_n)`；`E_comp(H)=Σ_n (C_n/p_n)·P_n·H`；`P = P_base + Σ_n u_n P_n + P_act`。计算图是能量账本的物理来源。

**定义 252（能量账本）** `E_avail(t) = Ê_t − ε_E(t) − E_reserve`，其中 `ε_E` 随温度/老化/内阻漂移增长，并在充电或静置时收缩。

**定义 253（安全回退能量）**
```
E_fb(x) = min_{s ∈ S_safe} cost(π_fb : x → s)
```
回退可行 ⇔ `E_avail(x) ≥ E_fb(x)`。

**定义 254（能量认证前缀）**
```
e*(A) = max{ e : cost(A[:e]) + E_fb(x_{t+e}) ≤ E_avail(t) }
```

**定义 255（联合认证前缀与可行域）**
```
k*_ST = min(k_VISTA, k_emotion, e*)
Ω = { (k,e) : k ≤ e, k ≤ k_VISTA, k ≤ k_emotion }
```

**定义 256（风险-能量优先级）** 对监测器 `n`，
```
μ_n = ΔRisk_n / E_n,  schedule = argmax Σ μ_n  s.t. Σ E_n ≤ B, deadline_ok
```

**定义 257（监测悖论与总损失）**
```
L(m) = L_s(m) + L_e(m) = a·e^{−λm} + b·m/E_avail
```

**定义 258（任务域与意图）** `M=(goal,T_return,risk_cap)`，MIN 施加 `M' = contract(M; π_intent, E_avail)`：能量越紧、意图越紧张，任务域收缩越强。

**定义 259（耦合崩塌）** 能量稀缺触发的调度降级恰好关掉捕获共发故障所需的监测器，导致「滞留危险态 ∧ 安全违规」同时发生。

**定义 260（耦合崩塌护盾 CCS）**
```
must = { top-1 风险监测器, fallback 监测器 }
must ⊄ chosen ⇒ FORCE_FALLBACK
```

**定义 261（deadline 优先级继承）** safety 话题消息继承其风险优先级，避免高优先级 safety 回调被低优先级感知回调阻塞。

**定义 262（J_stamina 证书）**
```
J_stamina = (J_ras, E_avail, e*, schedule_attestation, M', refuse_flag)
Valid ⇔ Valid(J_ras) ∧ e* ≥ k*_ST
        ∧ ∀n∈top-risk: deadline_miss_n = 0
        ∧ E_avail ≥ E_fb(x)
```

**定义 263（续航合同）** 对人类的承诺：保留 `E_reserve`，并在 `T_return` 内返航/停稳；不可满足时 MIN 必须显式协商或拒绝执行。

**定义 264（降级阶梯）** 监测器按 `μ_n` 降序成阶梯，只允许从底部降级；降级不得改变 top-risk 假设的证书有效性。

## 3. 关键算法伪代码

```python
# IP-234 EOL
class EnergyOSLedger:
    def __init__(self, reserve, eps0=0.02):
        self.reserve, self.eps, self.hat = reserve, eps0, 1.0
    def update(self, measured, nodes, dt, thermal=1.0):
        self.hat = measured
        self.eps = min(0.15, self.eps + 0.001*dt) * thermal
        self.e_comp = sum(n.power * n.duty for n in nodes) * dt
        return max(0.0, self.hat - self.eps*self.hat - self.reserve)

# IP-236 ECP
def energy_prefix(A, x0, e_avail, e_fb_fn, cost_fn):
    e_star, used, x = 0, 0.0, x0
    for i, a in enumerate(A):
        x = transition(x, a)
        used += cost_fn(a)
        if used + e_fb_fn(x) <= e_avail:
            e_star = i + 1
        else:
            break
    return e_star

# IP-235 RASP
def risk_energy_schedule(monitors, energy_budget, deadlines):
    order = sorted(monitors, key=lambda n: n.delta_risk / n.energy, reverse=True)
    chosen, used = [], 0.0
    for n in order:
        if used + n.energy <= energy_budget and deadline_ok(n, deadlines):
            chosen.append(n); used += n.energy
    return chosen, used

# IP-239 CCS
def coupled_collapse_shield(chosen, top_risk, fallback_monitor):
    if not {top_risk.id, fallback_monitor.id}.issubset({n.id for n in chosen}):
        return 'FORCE_FALLBACK'
    return 'CONTINUE'

# IP-237 MIN
def mission_intent_negotiate(M, pi_intent, e_avail, e_fb):
    margin = e_avail - e_fb
    if margin <= 0:
        return M.contract_to_safe()
    if pi_intent.risk > 0.6 or margin < 0.2*e_avail:
        return M.contract(scale=0.5)
    return M

# IP-243 STAMINA 闭环
def STAMINA_round(M, obs):
    V, T, P, L, P_cloud, W, tactile, img, depth, flow = obs
    e_avail = M.eol.update(M.measured_energy, M.ros_nodes, M.dt)

    face_gate = M.er.gateway.recognize(img)
    A = M.vista.ach.propose(M.lsf.fuse(M.usr.fuse(V, T, P, L)), H=M.vista.H)
    rho = M.vista.fir.signature(M.vista.stage.split(M.vista.residual_log))
    joint_post, _ = M.efs.synthesize(rho, face_gate)   # EFS-E 含 H_energy

    e_star = energy_prefix(A, M.x, e_avail, M.e_fb, M.cost)
    k_safety = M.csc_ras.certified_prefix_ras(A, joint_post, M.m_ras, M.alpha_chunk)
    k_st = min(k_safety, e_star)

    chosen, used = risk_energy_schedule(M.monitors, e_avail - M.e_fb(M.x), M.deadlines)
    if coupled_collapse_shield(chosen, M.top_risk, M.fallback) == 'FORCE_FALLBACK':
        return M.fallback(e_avail), {'refuse': True, 'e_star': e_star}

    M.mission = mission_intent_negotiate(M.mission, M.intent_pi, e_avail, M.e_fb(M.x))
    J = build_stamina_cert(M.j_ras, e_avail, e_star, k_st, chosen, M.mission)
    return M.dispatch(A[:k_st]), {'J': J, 'k_st': k_st, 'e_star': e_star,
                                  'sched': chosen, 'e_avail': e_avail}
```

## 4. 推导

**引理 11（回退可行性单调）** 若 `E_avail(t) ≥ E_fb(x_t)` 且 `a_t` 使系统更接近安全集，则 `E_avail(t+1) = E_avail(t) − cost(a_t) − E_comp(t) ≥ E_fb(x_{t+1})`。

**引理 12（能量前缀存在性）** `E_avail(t) ≥ E_fb(x_t) + c_min ⇒ e* ≥ 1`；否则 `e* = 0`，必须直接回落。

**引理 13（护盾局部无崩塌）** top-1 风险与 fallback 监测器可调度且观测正确时，CCS 触发回落不会进入耦合崩塌态。

**定理 11（安全-能量联合证书）** 在 A92–A96 下，
```
P(strand ∨ safety_violation) ≤ δ_E + Σ_n P(deadline_miss_n) + α_chunk
```
且 `schedule_attestation` 有效时 `J_stamina` 保持 Valid。

**定理 12（监测强度内点最优）** `L(m)` 严格凸，唯一最优 `m* = (1/λ)·ln(aλ·E_avail/b)`，且 `∂m*/∂E_avail = 1/(λ·E_avail) > 0`：可用能量越低，最优监测强度越低；CCS 将 `m*` 约束在不丧失 top-risk 覆盖的可行域内。

**定理 13（护盾无耦合崩塌）** 在 A92–A96 且 top-risk 观测正确时，CCS 不变式 ⇒ 任意能量水平下 `P(耦合崩塌)=0`。这把「省电降级」与「安全失效」解耦：可以降级，但不能降掉 top-risk。

## 6. 本轮最大风险

**一句话**：STAMINA 的全部定理都押在「能量模型可估且漂移有界、监测器风险排序正确、可安全降级监测器」上；一旦能量估计出现未建模漂移（温度/老化/负载突变）或降级顺序判错，调度器可能恰好关掉捕获共发故障的监测器，制造「没电 + 不安全」的耦合崩塌——把原本可被 VISTA/RAS 降级的故障，变成同时失去能量与安全兜底的灾难性失败。

**次级风险与缓解**：
1. **能量模型漂移**：用 INA226/RAPL 实测 + 卡尔曼估计，并保留保守 `ε_E` 上界；漂移超界时强制收缩任务域。
2. **风险排序错误**：用离线故障注入标定 `ΔRisk_n`，在线用残差更新；排序不确定时激活 CCS 的保守分支。
3. **降级引发新故障**：降级阶梯只动底部，且每次降级都重算 `J_stamina`；不 Valid 立即回落。
4. **executor 优先级反转**：QoS deadline + 回调组绑定 + DPI，压测 P99。
5. **实时算力**：EOL/RASP 均为 O(|N|) 级开销，控制在原 RAS 的 <1ms 增量内。
