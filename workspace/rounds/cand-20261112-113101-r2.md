# 第 58 轮（承接第 57 轮「少样本×跨模态×个性化」IP-133~138；灵感循环第 2 轮；本轮灵感：「用户需求分析」×「通用机器人平台」）

> 第 57 轮把安全的赌注从"模型置信"移到"证据质量"，用 q_φ 摊销先验、证据按模态分账、信任按操作者演化，把"证据说可信"做成五层纵深。但它仍默认两件事：**(a)** 要执行的任务/需求是给定的、正确的、无需检验的——系统只回答"我能否安全地做到"，从不回答"这是否是用户真正要的"；一个物理上完美安全、证据上无懈可击的承诺，完全可能是对错误问题的正确答案。**(b)** 一个平台只服务一个部署上下文——能力、证据、先验都可围绕这个上下文定制。通用机器人平台同时打破这两条默认：同一硬件/模型服务多用户、多任务、多环境，**需求必须被澄清与验证**，**能力必须有契约与适用域**，**跨租户复用必须被限域**。本轮两个灵感互锁：**用户需求分析**把"需求"从输入常量降格为**需要证据的假设**（意图信念 + 可执行验收 + 规格差检测 + 澄清探询）；**通用机器人平台**把"能力"从"我大概会"升级为**带证据适用域与降级模式的能力契约**，并把共享更新当作有爆炸半径的**共因事件**。核心命题由"证据说可信"升级为 **"需求经澄清、能力有契约、复用有适用域的可服务承诺"**：宁可在能力边界上说"做不到"，也不在错误的需求上做到完美。

核心矛盾：
- **H29（安全地做 vs 正确地做）**：物理证据只能证明"动作按假设执行"，不能证明"假设就是用户意图"；规格错（wrong specification）与证据假是正交的失效，前者甚至会让所有安全机制协同地把错误放大。
- **H30（澄清 vs 打扰）**：澄清降低需求不确定性，但要花用户时间、注意力与信任；问得太多是推卸责任，问得太少是替用户猜。更麻烦的是用户会口误、会改主意、会按字面而非意图回答，语言输入还可能被注入或胁迫。
- **H31（通用复用 vs 适用域）**：平台想复用能力、证据与需求先验来摊销成本，但证据只在声明的租户/上下文/版本/不变性内有效；越界复用是静默污染与负迁移——在甲租户验证的验收标准，被当成乙租户的默认。
- **H32（共享更新 vs 租户隔离）**：共享学习/固件更新能摊销经验，却把租户耦合成一个共因系统；一次坏更新就是全员失效，资源竞争还会在无人察觉时借用他人的安全裕度、悄悄收缩别人的安全包络。

## 0. 直觉与动机

**灵感 1（用户需求分析 → 需求即假设，而非输入常量）**
直觉：用户说"把箱子搬到二楼"，这是一条**观测**，不是意图本身。真实意图可能包含"别碰坏箱子""别走有人的楼梯""十分钟内到""其实我只是想清空一楼"。把话语当需求，就是跳过推断直接执行最字面的那个解。正确做法是维护一个**意图信念** b_rq(ψ)，把需求拆成可执行验收谓词 A_R、违反代价 C_R、可逆性 κ_R 与来源 ρ_R；安全承诺不要求"猜中唯一意图"，只要求**歧义集在动作上等价**，或对歧义集内所有意图都安全。语言只提供假设，验收测试才有签字权。

**灵感 2（需求探询 → 澄清是带成本的探针）**
直觉：问用户"是搬这个还是那个"本质是一次探针：有成本（打扰、时延、显得笨），有信息增益（可能缩小歧义集、可能改变动作）。第 57 轮的 VOI 可以直接搬过来：只有澄清会改变可行动作、且价值超过打扰成本时才问；否则在歧义集上取集合鲁棒动作，或对可逆低代价需求采用声明默认。澄清方式也应多模态——二选一、请求示范、沙箱预演、接受默认，按用户状态与代价选最省的一种。

**灵感 3（通用机器人平台 → 能力契约与诚实拒绝）**
直觉：通用平台的失败模式不是"能力弱"，而是"什么都敢接"。把能力登记为契约 c=(前置, 保证效果, 验证包络, 证据, 版本, 降级模式)：只有包络覆盖当前上下文、保证效果蕴含验收谓词、证据在适用域内达标，才算**可服务**。否则输出 HONEST_REFUSE 并解释"缺哪个能力/哪条证据/超出哪一维包络"。**诚实的边界**比虚假的通用更安全——"做不到"是一个合法且可解释的结果，静默降级为不安全动作不是。

**灵感 4（跨租户复用 → 证据适用域与需求污染）**
直觉：平台的价值在复用，但复用的前提是**适用域**。每条证据都带 σ=(租户/上下文集, 能力版本, 需求类, 不变性声明)，越界复用即污染。需求侧的污染更隐蔽：把 A 的验收谓词当作 B 的默认，会让 B 的"通过"毫无意义。因此跨租户只允许把需求类作为**先验**（走第 57 轮 OOD 门），不得直接当作已验证需求；新租户/新上下文退回逐项澄清与物理证据。

**灵感 5（平台共享更新 → 爆炸半径与安全单调）**
直觉：共享策略/元模型/固件更新是平台级**共因事件**。它必须像危险动作一样过证据门：影子运行 → 在不 disjoint 租户上 canary → 测量 → 灰度 → 可回滚；并且**安全单调**：未获租户同意，更新后每个租户的安全包络不得减小、降级契约不得放松。资源竞争必须按最坏降级契约核算，禁止"借用"他人的安全裕度。

**灵感 6（合流 → 三锁证据门与"探-澄-诺-演"）**
直觉：承诺要同时过三把锁：**物理锁**（第 57 轮证据门：动作按假设安全）、**需求锁**（意图歧义已收敛到动作等价、验收可执行可证伪、规格差小、硬约束满足）、**能力锁**（有契约能力、证据适用域覆盖本租户）。任一锁失败，顺序是：澄清 → 重路由到有契约的能力 → HONEST_REFUSE → L2 协商。三锁让"安全地做错事"至少多两次被拦下的机会，且每次拦下都指向一个可解释的缺口。

## 1. 形式化定义（增量：定义 145–150）

**定义 145（需求假设与需求契约 RIH）** 意图空间 Ψ；用户观测 u=(话语, 示范, 上下文)；需求信念 b_rq(ψ)=p(ψ|u,h) 按 proper scoring 校准。需求契约
R=(ψ̂, A_R, C_R, κ_R, ρ_R, τ_R)：
ψ̂ 为运行化意图；A_R:𝒳×𝒜→{0,1} 为**可执行、可证伪**的验收谓词；C_R 为违反代价；κ_R∈{可逆,半可逆,不可逆}；ρ_R∈{stated,elicit,demo,trace,default} 为来源；τ_R 为澄清预算。
歧义集 Ψ_α(u)={ψ: b_rq(ψ)≥Q_{1−α}(b_rq)}。**动作等价**：ψ∼_Π ψ′ 当且仅当对所有可达状态，在满足 A_R 与硬约束 H 下可行动作集合相同。**需求可运行** ⇔ Ψ_α 落在单一动作等价类，或存在策略对 ∀ψ∈Ψ_α 以 ≥1−β_rq 满足 A_R。**规格差** SpecGap(R;a)=P_{ψ∼b_rq}[a 满足 A_R 但违反 ψ]；承诺前须 SpecGap≤θ_sg。硬约束集 H（不伤害人、不越权、不可逆动作的物理安全）与用户需求**取合取**，任何来源（含用户本人）不得覆盖 H。

**定义 146（需求澄清探询 RCL）** 澄清动作 q∈𝒬={二选一, 请求示范, 沙箱预演, 接受默认}，成本 c_q（用户时延/打扰/信任损耗），观测模型 P(o|ψ,q)。需求价值
VOI_rq(q)=E_o[U(Ψ_α(o))]−U(Ψ_α)−c_q，
U 取"动作等价类数 × 违反代价"的负熵式度量。仅当 (i) 澄清可能改变可行动作 且 (ii) VOI_rq(q)≥θ_rq 时发问；否则在 Ψ_α 上取**集合鲁棒**动作，或（仅当 κ_R=可逆 ∧ C_R≤c_0）采用声明默认。澄清证据 EV-rq∈{elicit,demo,rq-trace} 按来源强度入账。**用户输入视为不可信声明**：须经复述回读或验收测试确认，冲突于 H 或检出注入/胁迫时拒绝并解释，而非照做。

**定义 147（能力契约与可服务性 CRG）** 能力注册表 𝒞={c=(pre_c, post_c, E_c, ev_c, ver_c, deg_c)}：前置条件、保证效果（分布或谓词）、验证包络 E_c（环境/上下文/载荷/时延/资源）、证据引用 ev_c、版本、降级模式 deg_c（竞争/磨损/传感器退化下的保守 post）。可服务性
Serv(r,R)=∃c: E_c⊇ctx(r) ∧ post_c⊨A_R ∧ ev_c 在适用域内达 1−β_cap ∧ pre_c/资源满足（按 deg_c 的**最坏**契约核算）。
不存在则输出 **HONEST_REFUSE**，并给出最小解释（缺哪个能力/哪条证据/超出哪一维包络）。可逆低代价需求允许"降级但告知"（degrade-with-notice）；不可逆高代价需求只许 refuse / 绕行 / L2 协商，**禁止**把超包络任务静默降级为不安全动作。

**定义 148（证据适用域与限域复用 SDR）** 证据项 e 带适用域 σ(e)=(租户/上下文集, 能力版本, 需求类, 不变性声明 inv)。对目标 t 复用 e 允许 ⇔ t∈σ(e) ∧ 版本匹配或持迁移证书 ∧ inv 覆盖差异 ∧ e 在来源 DAG 中未被重复计入（继承第 57 轮来源可追溯）。**需求复用**：租户 A 的需求类只能作为租户 B 的**先验**（走 OOD 门），不得直接当作 B 的已验证需求；**需求污染** ReqContam=P(B 的验收谓词被 A 的默认静默替换)。新租户/新上下文未覆盖 ⇒ 退回逐项澄清 + 物理证据，不做摊销。

**定义 149（多租户隔离与爆炸半径 TIB）** 平台更新 g（策略/元模型/参数/固件），租户集 𝒯。爆炸半径 BR(g)={t∈𝒯: 行为或安全包络变化 >ε_br}。规则：(I1) 共享更新必须 staged：影子 → 不相交租户 canary → 测量 → 灰度，全程可回滚；(I2) **安全单调**：未获租户同意，更新后每租户包络 E_t 不减、deg_t 不松；(I3) 资源竞争按 deg_c 最坏契约核算，不允许借用他人的安全裕度；(I4) 跨租户需求冲突升到平台仲裁并双边披露，禁止静默取舍。共享更新按**共因事件**对待：其证据门比单次承诺更严，要求 ≥2 个跨租户独立见证。

**定义 150（需求-能力证据门 RCG 与探-澄-诺-演 PCE++）** 承诺需三锁同时通过：
①**物理锁**：第 57 轮证据门（EV-probe*/visit/margin/xmodal/human）；
②**需求锁**：Ψ_α 动作等价或已澄清、A_R 可执行可证伪、SpecGap≤θ_sg、H 满足、对不可逆/高代价不得仅凭 default 来源；
③**能力锁**：Serv(r,R) 且证据适用域覆盖本租户/上下文、按最坏降级契约。
任一失败按序处理：澄清（RCL）→ 重路由到有契约能力 → HONEST_REFUSE → L2 协商。证书
J_r=(J_p, R, Ψ_α/b_rq, clarify_log, spec_gap_log, cap_ref/ver, deg_used, evidence_scope, tenant_id, br_log, update_ver)，继承 J_p 全检。

## 2. 关键算法伪代码（完整版见产物区）

```python
def requirement_contract(u, ctx, hist):            # IP-139 RIH
    b = belief_update(prior_rq(ctx, hist), u)      # 需求信念（校准）
    Psi = ambiguity_set(b, alpha_rq)               # 意图歧义集
    R = decompose(u, Psi)                          # (psi_hat, A_R, C_R, kappa_R, rho_R, tau_R)
    R.H_ok = implies_hard_constraints(R)           # 硬约束不可被需求覆盖
    R.spec_gap = spec_gap(R, b)                    # 措辞 vs 意图
    return R, Psi, b

def clarify_if_needed(R, Psi, budget, user):       # IP-140 RCL
    if action_equivalent(Psi) and R.spec_gap <= theta_sg:
        return R, []
    q = argmax(QUEUE, key=lambda q: voi_rq(q, Psi) - cost(q))
    if voi_rq(q, Psi) < theta_rq or budget.left <= 0:
        return robustify(R, Psi), []               # 集合鲁棒 / 声明默认
    o = user.ask(q, timeout=tau_rq)                # 用户输入 = 不可信声明
    if injection_or_conflict(o, R.H):
        return None, [('reject', 'hard_constraint_or_injection', q)]
    return update_contract(R, o), [q]

def serviceability(r, R, reg):                     # IP-141 CRG
    cands = [c for c in reg if covers(c.E, ctx(r))
             and post_implies(c.post, R.A_R)
             and evidence_ok(c.ev, scope(c), beta_cap)]
    if not cands:
        return None, explain_gap(reg, R, ctx(r))   # HONEST_REFUSE + 最小解释
    return min(cands, key=lambda c: conservative(c.deg)), None

def scoped_reuse(e, target, reg):                  # IP-142 SDR
    if target in scope(e) and version_ok(e, reg) and invariances_cover(e, target):
        return e                                   # 限域复用
    return None                                    # 不摊销，退回逐项澄清

def platform_update(g, tenants, metrics):          # IP-149 TIB
    shadow(g, all_tenants)
    if not envelope_nonincreasing(g, disjoint_sample(tenants)):
        return rollback(g)                         # I2 安全单调
    if blast_radius(g, metrics) > eps_br:
        return escalate(g, tenants)                # 平台仲裁，双边披露
    return staged_rollout(g, tenants)
```

## 3. 复杂度与正确性（要点）

| 组件 | 时间 | 空间 | 正确性关键 |
|---|---|---|---|
| RIH | O(\|Ψ\|·d) / 需求；更新 O(\|Ψ\|) | O(\|Ψ\|) / 租户 | 需求信念校准、H 不可覆盖 |
| RCL | O(\|𝒬\|·\|Ψ\|) + 人类时延 | O(\|𝒬\|) | 仅在改变动作时发问、输入当不可信 |
| CRG | O(\|𝒞\|) 查询（索引 O(log\|𝒞\|)） | O(\|𝒞\|) | 最坏降级契约、包络诚实 |
| SDR | O(\|σ\|)+DAG 校验 | O(\|e\|·\|σ\|) | 适用域完整、不重复计数 |
| TIB | O(\|𝒯\|) canary/回滚 | O(\|𝒯\|) | 爆炸半径有界、安全单调 |
| RCG/PCE++ | O(\|CP\|·(k_p+k_c+k_q)·(C_VOI+d)+...) | O(\|V\|+\|σ\|) | 三锁并联、四态完备 |

**正确性定理（Serviced Requirement Soundness, SRS）**：在 A33–A40（第 56–57 轮）上加
**(A41)** 需求模型校准：b_rq 声明校准、A_R 诚实可执行、H 恒被合取；
**(A42)** 能力契约健全：post_c 保证在包络与最坏降级下成立、证据适用域跟踪诚实；
**(A43)** 租户隔离：共享更新 staged、envelope 不减、爆炸半径 ≤δ_br；
**(A44)** 澄清成本/响应模型诚实，用户输入按不可信声明处理。
则：
(i) **需求健全性**：承诺动作满足真实意图的失效率 ≤ δ_f+ε_meta(k)+δ_probe+ε_h(w_max)+β_rq+θ_sg；
(ii) **服务健全性**：不存在超出声明包络的静默承诺；包络外一律 HONEST_REFUSE/degrade-with-notice；
(iii) **隔离性**：共享更新引起的单租户行为变化 ≤δ_br，且未同意租户的安全包络不降；
(iv) **交互单调性**：澄清、限域复用、平台更新只能经 (a) 需求信念更窄/更准 或 (b) 动作更保守（refuse/降级/更短超时）影响系统，不存在升险路径；
(v) **终止性**：PCE++ 在 k_probes+k_clarify 内终止于 {承诺, 重路由, HONEST_REFUSE, L2 协商, 安全停}。

**部署界**（对检查点与租户取联合界）：

```
P_safe ≥ 1 − Σ_cp (δ_f + ε_meta(k) + δ_probe + ε_h + δ_ood·α_conf + δ_xm·1[L1])
             − Σ_rq (β_rq + θ_sg + δ_H)
             − Σ_cap (δ_cap + δ_scope)
             − P(爆炸半径 > δ_br) − P(需求污染未检出)
```

关键：**物理锁保证"按假设做对"，需求锁保证"做的是对的问题"，能力锁保证"平台确实能做"**；三者正交，任何一把锁的失效都不该被另两把的通过所掩盖。

## 5. 风险与缓解

### IP-139 RIH（需求假设与需求契约）

```python
def requirement_contract(u, ctx, hist):
    b = belief_update(prior_rq(ctx, hist), u)      # 校准需求信念
    Psi = ambiguity_set(b, alpha_rq)               # {psi: b(psi) >= Q_{1-alpha}}
    R = decompose(u, Psi)                          # 运行化意图 + 验收谓词
    R.A_R = make_executable_falsifiable(R)          # 无验收 => 不可承诺
    R.H_ok = implies_hard_constraints(R)            # H = 不伤害/不越权/不可逆安全
    R.spec_gap = spec_gap(R, b)                     # 字面满足 vs 意图违反
    return R, Psi, b

def spec_gap(R, b):
    # 对满足 A_R 的动作，估计其违反真实意图的概率上界
    return max(prob_violates_intent(a, b)
               for a in actions_satisfying(R.A_R)
               if action_admissible(a, R.H))
```

### IP-140 RCL（需求澄清探询）

```python
def clarify_if_needed(R, Psi, budget, user):
    if action_equivalent(Psi) and R.spec_gap <= theta_sg:
        return R, []                                # 动作已等价，无需问
    cands = [q for q in QUEUE if q.cost <= budget.left]
    q = argmax(cands, key=lambda q: voi_rq(q, Psi) - q.cost)
    if voi_rq(q, Psi) < theta_rq or not cands:
        return robustify(R, Psi), []                # 集合鲁棒 / 声明默认
    o = user.ask(q, timeout=tau_rq)                 # 用户输入 = 不可信声明
    if injection_or_conflict(o, R.H):
        return None, [('reject', 'hard_constraint_or_injection', q)]
    return update_contract(R, o, provenance='elicit'), [q]

def robustify(R, Psi):
    # 在歧义集上选择满足所有 psi∈Psi 的动作；否则降级为声明默认（仅可逆低代价）
    if exists_action_satisfying_all(Psi, R.A_R, R.H):
        return strengthen(R, Psi)
    assert R.kappa_R == 'reversible' and R.C_R <= c0
    return default_with_notice(R)
```

```python
    cands = []
    for c in reg.index(ctx(r)):                     # 包络粗筛
        if not covers(c.E, ctx(r)):              continue
        if not post_implies(c.post, R.A_R):      continue
```

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| RIH | O(\|Ψ\|·d)/需求 | O(\|Ψ\|)/租户 | b_rq 校准、H 合取（A41） |
| RCL | O(\|𝒬\|·\|Ψ\|)+人类时延 | O(\|𝒬\|) | 仅改变动作时问、输入不可信（A44） |
| CRG | O(\|𝒞\|)（索引 O(log\|𝒞\|)） | O(\|𝒞\|) | 最坏降级、包络诚实（A42） |
| SDR | O(\|σ\|)+DAG 校验 | O(\|e\|·\|σ\|) | 限域复用、不重复计数（A42） |
| TIB | O(\|𝒯\|) canary/回滚 | O(\|𝒯\|) | 爆炸半径有界、安全单调（A43） |
| RCG/PCE++ | O(\|CP\|·(k_p+k_c+k_q)·(C_VOI+d)+...) | O(\|V\|+\|σ\|) | 三锁并联、四态完备 |

**正确性定理（Serviced Requirement Soundness, SRS）**
假设 A22–A32（第 53–55 轮）、A33–A40（第 56–57 轮）成立；**(A41)** 需求模型校准：b_rq 声明校准、A_R 诚实可执行、硬约束 H 恒被合取；**(A42)** 能力契约健全：post_c 在包络与最坏降级下成立、证据适用域跟踪诚实、来源 DAG 不重复计数；**(A43)** 租户隔离：共享更新 staged、envelope 不减、爆炸半径 ≤δ_br；**(A44)** 澄清成本/响应模型诚实，用户输入按不可信声明处理。则：

1. **需求健全性**：承诺动作满足真实意图的失效率 ≤ δ_f+ε_meta(k)+δ_probe+ε_h(w_max)+β_rq+θ_sg。
2. **服务健全性**：不存在超出声明包络的静默承诺；包络外一律 HONEST_REFUSE 或 degrade-with-notice（仅可逆低代价）。
3. **隔离性**：共享更新引起的单租户行为变化 ≤δ_br；未同意租户的安全包络不降、降级契约不松。
4. **交互单调性**：澄清、限域复用、平台更新只能经 (a) 需求信念更窄/更准 或 (b) 动作更保守（refuse/降级/更短超时/更小包络）影响系统，不存在升险路径。
5. **终止性**：PCE++ 在 k_probes+k_clarify 内终止于 {承诺, 重路由, HONEST_REFUSE, L2 协商, 安全停}。

**部署界**（对检查点与租户取联合界）：

```
P_safe ≥ 1 − Σ_cp (δ_f + ε_meta(k) + δ_probe + ε_h + δ_ood·α_conf + δ_xm·1[L1])
             − Σ_rq (β_rq + θ_sg + δ_H)
             − Σ_cap (δ_cap + δ_scope)
             − P(BR(g) > δ_br) − P(需求污染未检出)
```

关键：**物理锁做对动作、需求锁做对问题、能力锁确认平台能做**；三锁正交，任何一把的失效都不能被另两把的通过所掩盖；平台级复用与更新是共因风险，因此其证据门更严、作用范围必须显式限域。

## 6. 本轮最大风险

**一句话**：本轮把"做对的事"引入安全体系后，最大的风险从"安全地做错动作"升级为 **"跨租户、可复现、带证据地做错事"**——需求先验被平台摊销、共享更新一次性铺开，会让一个未被澄清的规格错误同时命中大量租户，形成共因失效；必须以硬约束不可覆盖、验收可执行、需求只作先验、证据限域、更新 staged 且安全单调五重护栏，宁可在边界上说"做不到"，绝不把错误需求规模化地做对。
