# 第 2 轮（灵感循环 v2：「自主导航」×「轨迹优化」）—— 从「块内重试」到「任务空间导航 + 块级轨迹优化」

> 承接第 1 轮 UIP-01~10。本轮先修正一个会推翻旗舰点实现方式的**接口事实**，再用两个新灵感词把「验证器驱动的重试」升级为「导航栈 + 轨迹优化」的双层架构。
> 关键结论：第 1 轮的 UIP-01（块内 k 步验证后重规划）在真实接口上**不能按原样实现**；本轮旗舰点改为 **UIP-11 TSN-TO（Task-Space Navigation + Trajectory Optimization）**——用全局语义路线解决「走偏/走丢」，用块级轨迹优化解决「这一块怎么走好」，两者都严格落在选手的 `observation→action` API 权限内。

---

## 0. 直觉解释（先给三句话）

1. **第 1 轮的 RHPV-V 像一个只盯着脚下几米路的司机。** 它能判断「这个子目标好像没完成」，但没有一张全局路线图，因此分不清当前是「走偏了」「路封了」还是「只是慢了一点」，只能盲目重试或跳过；重试一多，延迟方差和 episode 时预算都会反噬。
2. **自主导航之所以稳，不是因为局部控制器更强，而是因为它把问题拆成了五层。** 拓扑地图、定位/信念、全局路径规划、局部轨迹优化、恢复行为。桌面操作在「任务空间」里有完全同构的结构，只是「地点」变成了「语义路标」（接近、预抓、抓取、抬起、对准、插入、放置），「障碍物」变成了碰撞区、禁入区与不可达位姿。
3. **轨迹优化补上动作侧的另一半。** 既然评测端会**整块执行** `get_action` 返回的动作块、块内没有反馈，那么正确的做法不是「块内反复验证」，而是**把整个块当成一条待优化轨迹**，在固定算力预算内同时优化进度、平滑性、避碰与动作流形先验；块与块之间再由导航层做全局决策。

> **边界声明**：本轮不假设我们能控制移动底盘、电机阻抗、ROS 队列或执行层；「自主导航」是作为一种**计算架构**被引入任务空间，「轨迹优化」是优化我们有权返回的动作块本身。二者都不越过远程 API 的权限边界。

## 0.2 严谨定义（先给最小定义集）

**定义 1（任务空间拓扑图 TSTG）** 对任务 $k$，有向图 $G_k=(V_k,E_k)$。每个节点 $v\in V_k$ 是一个**语义路标**，带有地标描述子 $\phi_v: o\mapsto\mathbb{R}^d$、可观测谓词集合 $P_v$（如夹爪闭合、物体在手、物体到达目标位）、以及计分增量 $r_v\ge 0$。每条边 $e=(u,v)\in E_k$ 带有局部策略 $\pi_e$、期望耗时 $d_e$、风险 $c_e$、成功率 $q_e$。跨任务共享的通用节点（抓取、抬起、搬运、放置）构成共享子图 $G_0$，任务图 $G_k=G_0\cup G_k^{\text{spec}}$。

**定义 2（进度信念）** 在块边界维护信念 $b_t\in\Delta(|V|)$：
$$b_t(v)=\eta\,p(o_t\mid v)\sum_{u}b_{t-1}(u)\,T(u\to v;\,a_{t-1}),$$
其中 $p(o_t\mid v)$ 是地标似然（可用小 VLM 分类器或对比学习地标模型），$T$ 是转移模型。对路线 $\rho=(v_0,\dots,v_m)$，进度索引 $i_t=\arg\max_{v_i\in\rho}b_t(v_i)$，并加单调约束 $i_t\ge i_{t-1}$（允许带惩罚的回退）。置信度 $\kappa_t=\max_v b_t(v)$；当 $\kappa_t<\kappa_{\min}$ 或熵 $H(b_t)>H_{\max}$ 时判定为**走丢**。

**定义 3（步骤分感知路线规划）** 给定起始信念 $b_0$、目标节点集 $V_{\text{goal}}$、计分增量 $r_v$ 与边代价，求
$$\rho^*=\arg\max_{\rho}\ \mathbb{E}\Big[\sum_{v\in\rho}r_v+R_{\text{succ}}\mathbf{1}[\text{reach }V_{\text{goal}}]-\lambda\sum_{e\in\rho}d_e-\mu\sum_{e\in\rho}c_e\Big]$$
s.t. 总耗时 $\le T_{\text{budget}}$。图规模小，可用值迭代或带可采纳启发式的 A*；这是把第 1 轮 UIP-02「步骤分安全网」从后处理升级为**路线收益**。

**定义 4（块级轨迹优化）** 给定观测 $o_t$、当前边 $e=(u,v)$、基础策略 $\pi_{\text{base}}$、时域 $T_a$，求
$$A^*=\arg\min_{A\in\mathbb{R}^{T_a\times d}} J(A),$$
$$J=-w_p\sum_{j=1}^{T_a}\gamma^{j-1}\hat p(v\mid s_{t+j}(A))+w_l\big(-\log\pi_{\text{base}}(A\mid o_t)\big)+w_s\sum_j\|a_{j+1}-2a_j+a_{j-1}\|_2^2+w_c\sum_j\max(0,\delta-\text{clear}(s_{t+j}(A)))+w_u\sum_j\|a_j\|_2^2+w_tT_a.$$
其中 $\hat p$ 由学习到的动力学/世界模型给出；若世界模型不可靠，则退化为「末端进度估计 + 基础策略似然 + 当前帧避碰 + 平滑」四项，避免过度自信。

**定义 5（反馈-时域约束）** 令 $\Delta t=1/30$ s，$L_q$ 为单次调用的 $q$ 分位延迟（推理 + 网络 + 序列化）。评测端执行一个块需要 $T_a\Delta t$ 秒，因此要避免块间卡顿，必须
$$T_a\ \ge\ \Big\lceil \frac{L_q}{\Delta t}\Big\rceil+m,\quad m\ge 1.$$
有效反馈频率为 $30/T_a$ Hz，块间反应延迟为 $T_a\Delta t$。$T_a$ 因此是一个**全局设计变量**，不是随手写死的常数。

**定义 6（主动重定位）** 走丢时，从有限恢复动作库 $\mathcal A_{\text{reloc}}$（腕部相机扫视、移动到规范观测位、张开夹爪重新接近）中选择
$$a_{\text{reloc}}=\arg\max_{a\in\mathcal A_{\text{reloc}}}\mathbb{E}_{o'\sim p(\cdot\mid o,a)}\big[H(b_t)-H(b_{t+1})\big]$$
s.t. 安全与时间预算。它是导航里「原地旋转重定位」在操作任务中的对应物。

## 2. 两个灵感词的严格解读

### 2.1 「自主导航」：不是移动底盘，而是五层控制架构

| 导航概念 | 任务空间对应物 | 在本赛事中的抓手 |
|---|---|---|
| 拓扑地图 / 语义地图 | 从 32k 演示构建的语义路标图 TSTG | 离线建图 + 跨任务共享子图 |
| 定位 / 粒子滤波 / AMCL | 进度信念 $b_t$，判断当前在哪个路标/阶段 | 地标似然 + 转移模型 + 走丢检测 |
| 全局路径规划（A*/Dijkstra） | 步骤分感知的路线规划 $\rho^*$ | 计分点作为路标收益，先保底再冲成功 |
| 局部规划器 / MPC / DWA | 块级轨迹优化 $A^*$ | 在固定算力下优化整块动作 |
| 恢复行为（清代价地图、旋转重定位） | 主动重定位 + 路线修复 + 安全暂停 | 走丢/卡死/人为干扰时的有界恢复 |
| 代价地图 / 障碍物 | 立体深度得到的碰撞区、禁入区、不可达位姿 | 避碰惩罚与安全约束 |

**核心洞见**：第 1 轮的验证器只能回答「这个子目标完成了吗」，它无法回答「当前路线是否仍然可行」「是否应该改道」「是否已经走丢」。导航栈的价值不是更强的单点判断，而是**全局一致性与可恢复性**。

### 2.2 「轨迹优化」：不是底层控制器，而是「块」的优化

- 我们不能改电机阻抗、不能改执行层，但**能决定返回哪一条动作块**。因此轨迹优化的对象就是 $A\in\mathbb{R}^{T_a\times d}$。
- 因为块内开环，优化必须**整块进行**：优化目标要同时包含「朝下一个路标前进」和「整条块平滑、避碰、贴近演示流形」，而不是逐点贪心。
- 因为可信度会看延迟与动作规律性，优化必须是**固定算力预算**的：固定采样数 $K$、固定迭代数 $I$（MPPI/CEM），或固定去噪步数 $D$（扩散/流匹配细化）。不能按任务随机增加迭代，否则延迟方差会爆炸。
- 轨迹优化与导航层是互补的：导航层给「去哪」，轨迹优化给「这一块怎么去」。没有导航层，轨迹优化会在错误路标上越走越顺；没有轨迹优化，导航层只能发出粗糙的块，接触任务仍然抖动。

### 2.3 两词合流：TSN-TO 的一句话

**用拓扑图与信念把「操作失败」分解成「走偏 / 走丢 / 路封 / 局部动作差」四类，再分别用重规划、重定位、路线修复、块级轨迹优化处置。** 这比第 1 轮把所有失败都归给「子目标未完成 → 重试」要细，也更省 episode 时预算。

## 3. 瓶颈假设（本轮工作假设）

- **H1（走偏比抖动更致命）**：32 个任务里多步任务占多数（倒药、插网线、叠纸杯、折毛巾、装箱）。在成功率 <30% 的现实下，很多失败不是「手抖」，而是**阶段错了**——物体没抓稳就搬运、插头没对准就硬推、纸杯没套上就松手。全局路线 + 进度信念的边际收益应高于把局部策略再训强一点。
- **H2（步骤分是路线问题）**：若计分点确实存在，则「先到安全路标、再冲高风险终点」应作为**路线约束**，而不是失败后的补救；这能把部分失败转成步骤分。
- **H3（块级轨迹优化降异常）**：整块执行意味着块内动作的平滑性会直接进入可信度统计；固定预算的轨迹优化可降低 jerk 与异常跳变，同时不牺牲进度。
- **H4（$T_a$ 是硬约束）**：$T_a$ 必须满足反馈-时域约束；在 N 端口共享模型时，$L_q$ 会随并发上升，必须按最坏并发测。$T_a$ 太小会卡顿，太大会降低反应性，存在内部最优。
- **H5（共享路标带来组合泛化）**：把「抓取/抬起/搬运/放置」做成跨任务共享节点，任务专属节点只承载物体与目标，可把未见物品/背景的泛化压力从「整条策略」降到「节点选择 + 局部策略」。

## 4. 新框架：TSN-TO 的五层结构

```text
语言 + 首帧
   │
   ▼
[任务识别/路由] ──► 选择 G_k（共享子图 G_0 ∪ 任务专属）
   │
   ▼
[全局层] 进度信念 b_t ──► 走丢? ──是──► 主动重定位（有界）
   │                         │
   │                        否
   ▼                         ▼
[路线规划] 步骤分感知 ρ* ──► 边失败? ──是──► 路线修复（重试/绕行/跳过/暂停）
   │
   ▼
[局部层] 基础策略 π_base 产生 A_base
   │
   ▼
[块级轨迹优化] 固定预算 MPPI/CEM/扩散细化 ──► A*
   │
   ▼
[合规封装] 裁剪到 T_a、加 token、平滑限幅 ──► get_action 返回
```

**与第 1 轮的关键差别**：
1. 反馈发生在**块边界**，不是块内；所有「验证/重试/重规划」都在块边界做。
2. 失败被分成四类，处置方式不同；不再用一个 `max_retry` 统一处理。
3. 步骤分进入**路线收益**，不是失败后的补丁。
4. 轨迹优化是**固定算力**的，目的是同时降异常与提进度，而不是无限搜索。
5. $T_a$ 由反馈-时域约束和离线扫描共同决定，是提交级设计变量。

## 6. 本轮最大风险

**一句话**：语义路标图与进度信念的误差会在全局层被放大成「自信的错误路线」，同时新增的信念/验证/轨迹优化算力会抬高每块延迟并可能突破反馈-时域约束，导致既拿不到步骤分又触发可信度惩罚；因此必须以「离线校准 + 低置信回退基础策略 + 固定算力预算」三重护栏先证明代理指标，再上真机。

| UIP-18 | NAV-Bench 导航式离线评测 | 自主导航+轨迹优化 | 用回放 + 延迟模拟做可复现的代理指标 | ✅ |

**优先级**：UIP-11 是旗舰；UIP-12/13/14/15 是它的四个支柱；UIP-16/17 是可信度与恢复护栏；UIP-18 是迭代基础设施。建议按 18 → 12 → 13/14 → 15 → 11 → 16/17 的顺序落地：先把尺子和地图做出来，再上闭环。

## 1. 旗舰点深潜：UIP-11 TSN-TO

### 1.1 机制

每个块边界执行一次「感知—定位—规划—优化—封装」：

1. **定位**：用当前观测更新进度信念 $b_t$，判断是否走丢、当前处于哪个路标/阶段。
2. **全局决策**：若走丢且还有重定位预算，返回一个有界重定位块；否则若当前边失败或路线不可行，重规划路线；否则继续当前边。
3. **局部生成**：基础策略 $\pi_{\text{base}}$ 以观测、语言、当前边上下文为条件，产生 $A_{\text{base}}$。
4. **块级优化**：若当前边高风险/接触密集，或全局开关打开，则在固定算力预算内优化 $A_{\text{base}}\to A^*$。
5. **合规封装**：裁剪/补齐到 $T_a$，加 `meta.token`，做平滑限幅，返回。

### 1.2 与现有方案差异

- **对比开环 VLA（pi0/ACT/UnifoLM-VLA 式）**：不是整块盲执行到底，而是块边界用信念判断「是否还在正确路线上」，失败时不是简单重试，而是重定位/改道/跳过。
- **对比第 1 轮 RHPV-V**：验证器从「二值重试触发器」降级为「信念观测模型」；重试从「最多 2 次」升级为「四类失败、四种处置」；反馈从「块内」修正为「块边界」。
- **对比纯状态机**：路标图从数据里学，不是手写；路线收益包含步骤分与风险，不是固定脚本。
- **对比纯 MPC**：优化对象是评测端会整块执行的动作块，且优化预算固定，直接对齐延迟与动作规律性约束。

### 1.3 可行性 / 资源 / 落地步骤

- **可行性**：高。所有计算都在策略服务内部；`get_action` 仍返回合法动作块；`reset()` 可清空信念与路线；不需要额外接口。
- **资源**：32 个公开数据集（离线建图/训练地标模型/回放）；1 张推理卡可跑基础策略 + 小地标模型；轨迹优化可 CPU/GPU 固定预算；N 端口工程按 UIP-16。
- **落地步骤**：
  1. 建 NAV-Bench 回放器（UIP-18），固定 32 任务切分与延迟模拟。
  2. 建 TSTG v0（UIP-12）：分段、聚类、连边、共享子图。
  3. 训地标似然与走丢检测（UIP-13）；在回放上校准置信度。
  4. 实现步骤分感知路线规划（UIP-14）；先用均匀/学习权重近似官方计分点。
  5. 实现固定预算块级轨迹优化（UIP-15）；先在离线回放验证 jerk 与进度。
  6. 集成 TSN-TO（UIP-11）；扫描 $T_a$（UIP-16）；加恢复行为（UIP-17）。
  7. 小规模真机 pilot，校准代理指标后再提测。

### 1.4 风险

- 图建错 → 自信的错误路线。护栏：低置信回退到基础策略；路线规划加可达性检查；离线做节点纯度/边覆盖门槛。
- 信念误判 → 频繁重定位。护栏：滞回 + 置信度门限 + 重定位预算；先验证走丢检测 AUROC。
- 轨迹优化拖延迟 → 卡顿。护栏：固定 $K,I,D$；超预算直接返回 $A_{\text{base}}$；$T_a$ 按最坏并发延迟选。
- 步骤分定义未公开 → 代理权重偏差。护栏：先优化「阶段完成数」代理，官方计分点公布后替换。

## 2. 四个支柱的结构化定义

### 2.1 UIP-12 · TSTG（Task-Space Topological Graph）

**目标**：把 32 个任务约 3.2 万条演示变成一张可复用、可组合的语义路标图。

**建图流水线**：

1. **对齐**：LeRobot v3.0 数据按 30 fps 对齐 `action.*`、`observation.state.*`、4 路视频。
2. **分段**：用夹爪开合事件、EE 速度极小值、任务事件检测器（插入深度、物体位移、接触代理残差）把每条 episode 切成阶段。
3. **描述**：每个阶段取冻结视觉编码器（DINOv2/CLIP）的 head/wrist 特征 + EE 位姿 + 夹爪 + 语言嵌入，拼成 $\phi$。
4. **聚类**：任务内 HDBSCAN；跨任务用互可达性合并「抓取/抬起/搬运/放置」等通用节点，形成共享子图 $G_0$。
5. **连边**：相邻阶段连边；估计 $d_e$（平均时长）、$q_e$（阶段成功率）、$r_e$（计分增量代理）。
6. **训练**：每条边训一个轻量局部策略（BC/流匹配）；训地标似然 $p(o\mid v)$（对比学习或小 VLM 分类）。
7. **校验**：留出 episode 做路线回放，报告节点纯度、边覆盖、跨任务共享率、路线复现率。

**验收门槛（建议）**：节点纯度 > 0.8；边覆盖 > 0.9；跨任务共享节点数 ≥ 5；留出 episode 的路线复现率 > 0.85。

**风险**：分段事件在长任务（折毛巾、装箱）上不稳定。护栏：多事件投票 + 人工抽检 + 允许软分段（一个阶段可属于多个节点）。

### 2.2 UIP-13 · PB-Loc（Progress Belief Localization）

**目标**：把「当前在哪个阶段」变成概率信念，并检测走丢。

**更新**：
$$b_t(v)=\eta\,p(o_t\mid v)\sum_u b_{t-1}(u)\,T(u\to v;\,a_{t-1}).$$

**走丢判据**：$\kappa_t<\kappa_{\min}$ 或 $H(b_t)>H_{\max}$，并要求连续 $m$ 个块满足，避免抖动。

**主动重定位**：从有限动作库中选信息增益最大的动作；工程上可简化为「移动到最近的规范观测位 + 重新更新信念」，最多 $R_{\text{reloc}}$ 次。

**验收门槛**：走丢检测 AUROC > 0.85；误报率 < 10%；重定位后 2 个块内恢复路线比例 > 60%。

**风险**：地标似然对背景/光照敏感。护栏：只用腕部+头部低分辨率特征、做域增广（UIP-06）、低置信直接回退。

### 2.3 UIP-14 · SRP（Score-aware Route Planning）

**目标**：把步骤分直接写进路线目标。

**目标函数**：
$$\rho^*=\arg\max_{\rho}\ \mathbb{E}\Big[\sum_{v\in\rho}r_v+R_{\text{succ}}\mathbf{1}[\text{reach }V_{\text{goal}}]-\lambda\sum_{e\in\rho}d_e-\mu\sum_{e\in\rho}c_e\Big],$$
s.t. 总耗时 $\le T_{\text{budget}}$。

**安全网约束**：高风险终点前必须经过至少一个「安全里程碑」；若预算不足以完成全程，优先选择「收益/耗时」最高的前缀路线，保证拿到部分步骤分。

**求解**：图规模小（每任务几十个节点），用值迭代或 A* + 可采纳启发式；在线只重规划受影响的后缀，避免每块全图搜索。

**验收门槛**：相比「成功优先」路线，步骤分代理 +15%，成功率不降；相比贪心最近路标，路线总收益 +10%。

**风险**：官方计分点未公开，代理权重可能偏。护栏：先做均匀权重与学习权重两版，官方公布后校准。

### 2.4 UIP-15 · CMPPI（Chunk-level Model-Predictive Trajectory Optimization）

**目标**：在固定算力下优化整块动作。

**目标函数**：见想法区定义 4。工程上分三档，按算力预算选择：

- **L0（仅当前帧）**：$\hat p$ 用当前观测的末端进度估计；代价 = 进度 + 基础策略似然 + 平滑 + 当前帧避碰。最稳、最快。
- **L1（短时预测）**：用轻量动力学模型预测 $T_a$ 步的 EE/物体状态；代价加预测进度与预测避碰。
- **L2（世界模型）**：用 Unitree `UnifoLM-WMA-0` 风格模型做 latent rollout；只在离线或高算力时启用。

**优化器**：MPPI/CEM，固定 $K$ 个采样、$I$ 次迭代；或扩散/流匹配细化，固定 $D$ 步。所有档位都必须有「超预算回退到 $A_{\text{base}}$」的分支。

**验收门槛**：动作异常率（跳变率/峰度/jerk）相对基础策略 −50%；离线进度不降；延迟 p95 增量 < 20 ms。

**风险**：世界模型误差导致「优化出自信的坏块」。护栏：L0 默认；L1/L2 只在离线验证通过后启用；代价里保留基础策略似然作为强正则。

## 3. 关键算法（旗舰 UIP-11 伪代码）

```python
class TSNTOPolicy:
    def __init__(self, graphs, base_policy, belief, route_planner,
                 traj_opt, cfg):
        self.graphs = graphs          # 任务 -> TSTG
        self.base = base_policy       # VLA / BC 基础策略
        self.belief = belief          # 地标似然 + 转移模型
        self.planner = route_planner  # 步骤分感知 A*/VI
        self.opt = traj_opt           # 固定预算 MPPI/CEM/扩散细化
        self.cfg = cfg                # T_a、预算、阈值、token

    @property
    def metadata(self):
        return {
            "control_space": self.cfg.control_space,
            "obs_delta_indices": self.cfg.obs_keys,
            "image_resize": self.cfg.image_resize,
            "action_chunk_size": self.cfg.T_a,
            "token": self.cfg.token,
        }

    def reset(self):
        self.belief.reset()
        self.route = None
        self.edge_i = 0
        self.fail_count = 0
        self.reloc_left = self.cfg.reloc_budget

    def get_action(self, obs):
        self.belief.update(obs)

        if self.belief.lost() and self.reloc_left > 0:
            self.reloc_left -= 1
            return self._pack(self._relocalize(obs), obs)

        if self.route is None:
            task = self._task(obs)
            self.route = self.planner.plan(self.belief, self.graphs[task])
            self.edge_i = 0

        edge = self.route[self.edge_i]
        if self._edge_failed(obs, edge):
            self.route = self.planner.repair(
                self.belief, self.route, self.edge_i)
            self.edge_i = 0
            edge = self.route[self.edge_i]

        A = self.base.get_action(obs, edge)
        if edge.risky or self.cfg.always_opt:
            A = self.opt.refine(A, obs, edge, budget=self.cfg.opt_budget)

        if self._edge_done(obs, edge):
            self.edge_i += 1
            self.fail_count = 0

        return self._pack(A, obs)
```

**四类失败与处置**：

| 失败类型 | 判据 | 处置 |
|---|---|---|
| 走偏 | 信念 argmax 偏离路线，但置信度高 | 重规划到当前实际路标的后继 |
| 走丢 | $\kappa_t$ 低 / 熵高，连续 $m$ 块 | 主动重定位，有界次数 |
| 路封 | 当前边连续 $R$ 块无进度，或重试仍失败 | 路线修复：换边/绕行/跳过可选节点/安全暂停 |
| 局部动作差 | 进度在走但 jerk/异常高 | 块级轨迹优化；必要时缩短有效运动（hold 补齐） |

## 4. 反馈-时域约束与 $T_a$ 选择（UIP-16）

**推导**：评测端执行一个块需 $T_a\Delta t$ 秒；策略在块结束后才能收到新观测并计算下一块。若单次调用延迟 $L>T_a\Delta t$，机器人会在块末等待，形成卡顿；可信度会记录延迟波动，卡顿还会拉低 episode 成功率。因此
$$T_a\ \ge\ \Big\lceil\frac{L_q}{\Delta t}\Big\rceil+m,\quad \Delta t=1/30\text{ s},\ m\ge 1.$$
N 端口共享模型时，$L_q$ 取**最坏并发**下的 $q=0.95$ 分位，而不是单端口空载延迟。

**选择流程**：

1. 在目标部署拓扑下压测 N 端口并发，测 $L_{0.5},L_{0.95},\sigma_L$。
2. 由约束得 $T_{\min}=\lceil L_{0.95}/\Delta t\rceil+m$。
3. 在离线代理上扫描 $T_a\in[T_{\min},T_{\max}]$（如 2..16），用
   $$\hat S(T_a)=\widehat{\text{succ}}(T_a)+\widehat{\text{step}}(T_a)-\lambda_s\widehat{\text{stall}}(T_a)-\lambda_v\widehat{\text{var}}(T_a)-\lambda_a\widehat{\text{anom}}(T_a)$$
   选 $T_a^*$。
4. 真机 pilot 校准；冻结后写入 `metadata`，不要在提交后动态改。

**注意**：`T_a=1` 反馈最快，但调用频率 30 Hz，推理吞吐很可能跟不上；`T_a=16` 省调用但反应慢、块内开环长。不要用「运动 k 步 + hold」来假装缩短反馈——hold 会浪费 episode 时间，且反馈周期仍是 $T_a$，只应在接触前微调等少数场景使用。

## 6. 指标定义（避免自欺）

- **成功率**：任务完成率（官方口径）。
- **步骤分**：官方 Scoring Steps；未公开时用「已完成阶段数 × 权重」代理，并同时报告均匀权重与学习权重两版。
- **走偏率**：块边界信念 argmax 不在计划路线上、且进度索引未前进的比例。
- **走丢检测 AUROC**：以人工标注/回放真值为标签。
- **卡顿率**：$L>T_a\Delta t$ 的块边界比例。
- **动作异常率**：逐维跳变率、jerk 超阈值比例、峰度偏离演示分布的比例。
- **可信度复合分**：$-\big(\lambda_1 p95(L)+\lambda_2\sigma_L+\lambda_3\text{anom}\big)$，仅用于内部比较，不假设官方公式。
- **路线最优性 gap**：离线已知最优路线收益与在线路线收益之差。

## 8. 本轮的明确负结果与待验证项

- **负结果（接口层）**：第 1 轮 UIP-01 的「块内 k 步验证」在真实评测循环中不可实现；UIP-10 的「按任务在 joint/ee 间仲裁」在单次提交内不可实现。两者都已在本轮改写/封存。

- **待验证（方法层）**：TSTG 在长任务上的分段稳定性、地标似然在背景/干扰物变化下的校准、块级轨迹优化的真实延迟增量、代理指标与真机的相关性。这四项必须先用 NAV-Bench + 小规模 pilot 验证，不能直接假设成立。

## 9. 本轮最大风险（承接想法区 §6）

**一句话**：语义路标图与进度信念的误差会在全局层被放大成「自信的错误路线」，同时新增的信念/验证/轨迹优化算力会抬高每块延迟并可能突破反馈-时域约束，导致既拿不到步骤分又触发可信度惩罚；因此必须以「离线校准 + 低置信回退基础策略 + 固定算力预算」三重护栏先证明代理指标，再上真机。
