# 第 8 轮 · POT-PSC：对象级持久状态已被占坑，下一步是“预测性状态一致性 + 人类对抗修复”

> 检索/复核日期：**2026-10-25（UTC）**。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「通用机器人」「实例分割」「用户测试」。
>
> 本轮最重要的发现不是“又想到一个模块”，而是：**我原本想写的“实例 grounding 的持久对象账本（IGPOS）”已经被 POT-VLA 做了，而且就是在 Unitree G1 上做的**。POT 用 role-indexed 3D object records 同时条件化动作和验证，G1 上 39/80→71/80；它的结论段还把 **human interaction** 列为 future work。继续把“对象级持久状态”当新意，就是重复造轮子。因此本轮的主判断改成：**把 POT 的“事后几何谓词”升级为“事前预测 + 事中检测 + 事后修复”的预测性状态一致性（PSC），并用人类对抗测试（HUT）系统制造和标注状态分歧。**

## 0. 先说不讨喜的：POT 已经覆盖了“对象级持久状态”

### 0.1 POT 做了什么（必须承认的最近邻）

POT-VLA（arXiv 2607.18016，v2 2026-07-26，[S13]）的核心主张与“实例分割 + 持久对象状态”几乎一一对应：

- **role-indexed 3D object records**：每个任务实体绑定到 TARGET / DESTINATION / SUPPORT / HANDOVER_PARTNER 等角色槽；K=8 个槽、每槽 33 维特征；记录包括 2D box、3D centroid、3D extent、visibility、confidence、relations。
- **同一份 memory 同时给 action expert 和 predicate verifier**：动作前用 object tokens 条件化，动作后用刷新后的同一份 memory 做几何谓词校验；POT 把失败模式命名为 **object-state divergence**。
- **真机结果（POT 自己的 8 任务集，不是 UniBot 32 任务）**：Unitree G1、8 个真实任务族，匹配的 direct GR00T-N1.7 baseline 从 **39/80 → 71/80**；Being-0 对齐的 service suite 44/50，对照论文报告 37/50。
- **输入**：RGB-D + SAM3 masks；不假设 simulator、physics engine 或 learned dynamics。
- **作者自述的 future work**：active multi-view memory、richer contact、dexterity、**human interaction**。

这四条合起来，基本封死了“对象级 persistent object tokens 是新一轮创新”这条路。上一轮我写的 IGPOS 如果原样提交，审稿人一句“这不就是 POT 吗”就会结束讨论。

### 0.2 POT 没做什么（本轮真正的缝）

POT 很强，但它仍然是 **“事后谓词”** 系统：

1. **验证发生在 chunk 执行之后**。POT 在 `M_{t+H}` 上检查谓词是否成立；如果人在 chunk 中途把碗移走、把拉链拉开、把插头拔起，策略可能已经执行完一整段无效动作，甚至已经“以为完成”。它擅长发现 **false completion**，不擅长在动作前/动作中预测 **state divergence**。
2. **对象级，不是部件级**。POT 的 record 是“碗/杯子/抽屉/托盘”这一级；毛巾的折叠角、拉链的 slider/teeth、包的开口、盒盖的 hinge、耳机左右件，都没有一等公民表示。UniBot 的 T16/T19/T23/T31 等软体/铰接任务，失败往往发生在 **对象内部状态**，不是对象在哪里。
3. **人类交互只是 future work**。POT 没有系统的人类扰动协议、没有“分歧发生时刻”的标注、没有 held-out user 的泛化评估；而 UniBot 正好有 **20% 的人为干扰轴**。
4. **输入是 RGB-D，UniBot 只给 RGB**。POT 用 SAM3 + depth；UniBot 给的是 4 路 RGB（头戴双目已矫正），没有 depth 通道。双目可以恢复 metric depth，但需要自己补 stereo、掩码蒸馏、单 checkpoint 合规；这些是工程门槛，不是研究新意。
5. **POT 的任务是 loco-manipulation，不是 32 项桌面任务 + 5 轴泛化**。POT 的 role slot 数量、谓词库、恢复策略都没有覆盖 UniBot 的 32 任务评分步骤与人为干扰剧本。

### 0.3 于是本轮的主判断

**不要再做一遍 POT。把 POT 当底座，做它没有做的“预测性状态一致性（PSC, Predictive State Consistency）”：**

```text
POT：      动作 → 执行 → 刷新 object memory → 几何谓词 → 失败后恢复
PSC：      动作 → 预测 object/part state → 执行 → 观测 → 分歧分数
                 ↑                                      │
                 └──── 重观测 / 减速 / 回滚 / 重抓 / 重规划 ┘
```

一句话：**POT 解决“对象还在不在、关系成不成立”；PSC 解决“在动作做完之前，我知不知道对象状态已经要分叉了”。**

## 1. 本轮新核实的事实

### 1.1 排名规则修正：步骤分是 tie-breaker，不是 60% 权重

中文手册原文（[S2]，2026-10-25 复核）：

- “每个任务在不同的泛化评测场景中进行 **10 次测试**，计算每个任务的平均成功率，平均过程分，并计入排行榜。”
- “实时榜单按 32 个任务的 **总平均成功率** 进行排序，成功率相同时按 **总平均步骤分** 排序，若仍相同，则提交日期较早的模型排序靠前。”
- “每个任务执行 10 次独立运行……5 种泛化类型，每种类型各出现 **2 次**。”
- “每个任务单次真机执行最大允许执行时间为 **180 秒**，超时记为失败。”
- “所有任务须基于 **同一模型** 完成，不得混合使用多个模型一起进行测试。”

这直接修正上一轮的两个错误：

1. **排名不是“成功率 + 步骤分”的加权和**。步骤分只在成功率相同时决定名次；网站首页“综合排序”是概括，手册的排序规则更具体。
2. **不应把约 60% 的预算押在“步骤分大头/终局放置”上**。终局放置仍是成功闸门，但部分分本身不是主目标；先保整任务成功，再在成功率平台期用步骤分做 tie-break 诊断。

### 1.2 榜单仍是占位，不能拿 task-level 数字推理

- `leaderboard.html` 仍是 “Coming Soon”；`leaderboard_data.json` 的 `generated_from=gen_leaderboard.py`，8 个模型 × 32 任务 = 256 条 `task_metrics` 是脚本生成（[S4][S5]）。
- 占位数据里 MolmoAct2 29.7/39.0、WALL-OSS-0.5 28.5/38.9、DreamZero 27.9/37.9、Spirit-v1.5 25.9/34.4、DM0 23.5/31.7、PI-0.5 22.8/30.6、GigaBrain-0 22.6/29.5、GR00T N1.5 20.5/28.1（成功率/步骤分）。
- 用户“榜首 <30%”的前提与占位数据一致；但 **这不是真实榜单**。本轮只把它当难度先验，不用来推断轴级瓶颈或模型强弱。

**结论：UniBot 不是 32 个独立的抓放任务，而是“几个最弱 tag × 32 个实例 × 5 个轴”。** 只抠终局放置，会错过 temporal/softbody 这两个更深的洞。

### 1.4 头部方案：都在补“语义/动作”，很少补“状态”

| 方案 | 公开做法 | 与本轮相关的瓶颈 |
|---|---|---|
| MolmoAct2 [S23] | action reasoning + depth-aware perception tokens + 空间计划 + flow matching | 批量开环执行，chunk 中不反应；对本轮是“缺少事中检测”的典型 |
| WALL-OSS-0.5 [S18] | 4B VLA、3B VLM、20+ embodiments、100 万+ trajectories、gradient-bridged co-training；微调后 60.5%，比 π0.5 高 17.5% | 单帧输入为主（限制部分指出长程时序记忆弱）；强在预训练，不强在状态 |
| DM0 [S19] | 2.4B embodied-native VLA、三阶段预训练、spatial CoT、hybrid gradient | RoboChallenge 上 specialist 62.00% vs generalist 37.33%，约 25pp 通才 gap：任务干扰/状态共享不足 |
| Spirit-v1.5 [S20] | Qwen3-VL-4B + DiT action head、开放多样数据、40% fewer iterations | 宣称 51% success；强在数据规模，弱在软体/时序 |
| GigaBrain-0 [S21] | world-model 生成数据 + RGBD + embodied CoT，3B，51.67% | 依赖 RGBD；UniBot 只有 RGB（但双目可恢复深度） |
| DreamZero [S22] | 14B world-action model、video diffusion、7Hz、约 2× 泛化 | 算力/延迟重；适合当辅助，不适合当主路径 |
| π0.5 [S17] | VLM + flow matching、异构 co-training、开放世界泛化 | Table30 42.67%；单帧/短上下文，temporal/softbody/precise3d 仍弱 |
| GR00T N1.5 [S24] | Eagle VLM + DiT、双系统、FLARE future latent alignment | 人形适配好；桌面精细操作与状态持久性仍不足 |

共同点：**大家都在把语义先验、动作生成、数据规模做得更强；很少有人把“对象/部件状态”做成一个显式的、可预测、可验证、可修复的层。** POT 是例外，但它只做到对象级、事后谓词。

### 1.5 数据与双目：UniBot 具备做 metric state 的物理条件

- 32 个 HF 数据集，合计约 **33,276 episodes / 169h**；HangCup 实测 **1,043 episodes、194,564 帧、30fps**，`lastModified=2026-10-14`（[S9][S10]）。
- 4 路相机均为 **480×640**：`head_stereo_left/right`、`wrist_left/right`；数据集没有 depth 视频，但头戴双目 `rectified=true`，基线 `T≈[-58.2526, -0.1675, 0.5786] mm`，左右 K 约 fx=282，cx=311.5/330.0，cy=256.6/249.5（[S10]）。
- 双目深度：`Z = f*B/disparity`。0.5m 处视差约 33px，1m 处约 16px；桌面 0.3–0.8m 的工作区间足够做厘米级 3D 状态。
- 每任务 `tasks.parquet` 有 **5 条英文复述**（`@` 分隔）；评测语言很可能是其中之一或同义改写。
- 每个 `tasks_v2/<slug>/info.json` 有 `score_steps`、难度、`generalization` 备注；T27 的备注示例：`human_1=把粉色碗向下移动`、`human_4=叠了第二个之后拿下第二个`。

### 1.6 API 与单模型：PSC 必须在一个 checkpoint 内完成

- 观测：4 路 RGB、双臂关节/EE 位姿、夹爪、下半身、`observation.language` 单字符串；`obs_delta_indices`、`image_resize`、`action_chunk_size` 可自定；joint/ee 动作空间互斥（[S8]）。
- 评测 N 台机器人，要求 **N 个连续端口，从 8765 开始**，端口数恰好等于 N；需并发与状态隔离。N 未公开。
- 单模型规则意味着：**不能推理时外挂 SAM2/SAM3 再调用第二个策略模型**。默认方案是把 mask head 蒸馏进唯一 checkpoint；SAM2/MobileSAM2 只在离线做 pseudo-label。
- 180s 预算足够做 1–3 次主动重观测/回滚；但长程任务（T16/T17/T31）要限次数。

### 1.7 用户测试/对抗数据：ADC 是最强证据

ADC（Adversarial Data Collection，AgiBot G1 + π0，[S25]）让第二个“adversarial operator”在 teleoperator 执行时实时移动物体、改背景、改指令：

- 只用 **20% 的 ADC 数据**，在静态/动态/位置泛化上就超过 **100% 传统数据**。
- 动态视觉扰动下，ADC 模型成功率 **0.88**；baseline **完全失败**（0.0）。
- 关键不是“数据更多”，而是“**恢复行为被压缩进同一条演示**”：re-grasp、轨迹重规划、指令切换都变成了监督。

这与 UniBot 的 20% 人为干扰轴、以及 T27/T19/T14 等“先完成再撤销”的备注高度同构。但注意：**官方计分评测不允许人类接管**。所以 HUT 只能用于离线数据采集、阈值校准、发布门，不能用于在线“人帮忙”。

### 1.8 相关方法的边界：PSC 不是又一个“大 world model”

| 方法 | 做了什么 | 与 PSC 的边界 |
|---|---|---|
| POT [S13] | 对象级持久 records + 几何谓词 | 事后验证；无预测动力学、无部件、无 HUT |
| DeMaVLA [S26] | 多类别折叠 VLA，5,000h 预训练 + HITL DAgger，76.3→92.5 | 强策略/强数据；不是通用对象/部件状态层 |
| FoldBack [S27] | 长程衣物折叠，自校正/回滚/重试，45.7→75.2 | 衣物专用；没有跨 32 任务的状态表示 |
| VLA-Corrector [S28] | learned verifier + stage-aware prompt recovery，70.9→82.6 | 视觉-本体-动作历史的执行状态；没有对象级 3D 状态 |
| CoRe [S29] | 推理时反事实重对齐，最多 +85pp | 不改策略；没有持久对象账本 |
| SocialVLA [S30] | 人类反应检测→暂停/纠正，G1 | 人在环运行时；不是自主状态分歧检测 |
| FATE-VLA [S31] | 主动 failure test generation，最多 +29.7% failures | 评测生成；不修复 |
| SERF [S32] | 时空特征地图 + VLA，长程移动操作 | 场景级 memory；不是部件级状态 |
| Oat-VLA [S33] | 对象中心 token 压缩 | 效率/表征；不是状态验证 |
| RoboSeg [S34] / UniPart [S35] | 部件级语义重建/零样本 3D 部件分割 | 感知层；不接 VLA 状态与恢复 |

**PSC 的位置**：在 POT 的对象 records 上，加一个**小的、任务无关的 object/part dynamics head**，用预测误差做 state divergence 分数；再用 HUT 训练/评估修复策略。它不是 14B video world model，也不是又一个新的 VLA 主干。

## 2. 三个灵感词，各自钉到事实上

### 2.1 通用机器人：缺的不是更大的 VLA，而是任务无关的状态接口

DM0 在 RoboChallenge 上 specialist 62.00% vs generalist 37.33%，说明“一个模型跑多任务”会遇到严重的任务干扰。原因之一是：每个任务的对象配置、容器关系、成功谓词都不同，策略必须用同一套视觉-语言特征去隐式编码 32 套状态。

POT 的 role slot 是一个正确的方向：**用任务无关的 schema（TARGET/DESTINATION/SUPPORT/…）承载任务相关的实体**。PSC 继续沿这个方向：

- 一个 `StateRecord` schema，32 个任务共用；
- 一个 `Predicate` 库，由 SSG 从任务描述编译；
- 一个 `DynamicsHead`，所有任务共享；
- 一个策略 checkpoint，不按任务分 LoRA/head。

“通用”不等于“模型更大”，而是“**状态接口更通用**”。这也是为什么 PSC 的收益应该体现在 **跨任务 breadth**（无零任务、任务间方差下降），而不只是单任务峰值。

### 2.2 实例分割：不是输入增强，而是状态传感器 + 验证通道

对象级实例分割已经被 POT 证明有用；本轮不再把它当新意。真正还没被吃透的是：

1. **部件级实例**：毛巾角、拉链齿/滑块、包口、盒盖 hinge、耳机左右件、针管活塞。软体/铰接任务的失败常发生在“对象内部”，对象级 mask 看不出来。
2. **双目 metric**：UniBot 没有 depth，但头戴双目可恢复度量 3D；这使“预测位移 2cm”与“实际位移 2cm”可比，而不是只比 2D IoU。
3. **分割作为验证通道**：同一套 mask 既给策略做 state token，又给 PSC 做预测/观测比对；不是两套感知。
4. **单 checkpoint 合规**：mask head 蒸馏进主模型；SAM2 只离线。

**关键区别**：POT 用 mask 建 object record；PSC 用 mask 建 **可预测的 object/part state**，并把预测误差变成恢复触发信号。前者是“知道对象在哪”，后者是“知道对象状态是否要分叉”。

### 2.3 用户测试：不是上线时让人帮忙，而是离线制造“状态分歧”

官方人为干扰轴占 20%（每任务 2/10），且备注是“移动/撤销/重置”而不是“人手挡一下”。这意味着失败不是简单的视觉遮挡，而是 **物理状态被改变**：

- 碗被向下移动 → 目标位姿变了；
- 叠了第二个之后被拿走 → 已完成步骤被撤销；
- 拉链拉上之后被拉开 → 完成谓词从 1 变 0；
- 插头被拔起 → 插入关系被破坏。

ADC 证明，这种“执行中被人改状态”的数据极其高效。但 ADC 是人类 teleop 采集；我们要把它变成 **可重复的 HUT 协议**：

- 3 个角色：teleoperator（采演示/恢复）、adversarial user（按剧本+即兴扰动）、blind evaluator（打分）。
- 完整 8 个代表任务 × 5 轴 × 2 次 × 3 用户 = 240 episodes；pilot 砍到 4 任务 × 5 轴 × 2 × 2 = 80。
- 标注：扰动时刻、对象 ID、期望状态、观测状态、分歧分数、恢复动作、恢复结果。
- 留出：1 个未见用户、2 个未见任务、1 类未见扰动，测泛化。
- 合规：HUT 只离线；计分跑不接人；数据来源与用途写进模型卡。

**HUT 的产物不是“更多数据”，而是“状态分歧的有标签事件”**：这正是 PSC 的监督信号。

## 3. 失败模型：POT 的“事后谓词”漏掉了什么

把 POT 的 `object-state divergence` 再往前推一步，定义三个时间点：

```text
t:     当前 object memory M_t
t+H:   策略执行完一个 chunk，POT 在这里刷新 M_{t+H} 并检查谓词
```

POT 能发现：`M_{t+H}` 不满足谓词 → 失败/恢复。
POT 不能提前发现：在 `t` 到 `t+H` 之间，`M` 已经被外力改变，策略正在执行错误动作。

### 3.1 三类分歧

| 类型 | 触发 | 例子 | POT 的事后谓词 | PSC 的预测一致性 |
|---|---|---|---|---|
| D1 外力改状态 | 人移动/拿走/撤销 | T27 叠第二个后拿走；T19 拉上后拉开；T24 传送带把物体放回起点 | 只能在 chunk 后失败 | 预测 `M_{t+H}` 与观测比对，提前减速/重观测 |
| D2 对象内部状态变化 | 软体/铰接 | 毛巾折角滑落、拉链只咬合一半、盒盖没扣上、针管回吸 | 对象级谓词太粗，容易 false success | 部件级状态图 + 预测误差 |
| D3 身份/角色错配 | 干扰物/未见物/遮挡 | 抓错杯子、把干扰物当目标、容器被换 | POT 的 role slot 可部分处理 | 预测角色/关系，检测 ID switch |

### 3.2 为什么“预测”比“事后谓词”更早、更省

- 180s 的预算里，一次错误 chunk 可能浪费 2–5s；长程任务 T16/T17/T31 更贵。
- 事后谓词只能在 chunk 边界检查；如果 chunk=16 步、5–10Hz，最多 1.6–3.2s 才检查一次。PSC 可以在 chunk 内用短窗预测/观测比对，提前触发。
- 对人为干扰，越早发现越容易回滚；等物体被拿走再重抓，可能已经丢了这个 trial。
- 对软体，几何谓词难写；学习到的部件状态预测可以给出“拉链没闭合”的连续分数，而不是二值失败。

### 3.3 但预测不能取代谓词

PSC 不是要替换 POT 的几何谓词，而是加一层 **早期预警**：

- 预测分歧高 → 主动重观测/减速/回滚；
- 谓词失败 → 确认失败并修复；
- 两者一致 → 继续。

这样既保留 POT 的可解释性，又补上“事中”这一层。

## 4. 主判断：POT-PSC

### 4.1 一句话

**把 POT 的“执行后谓词”升级为“执行前预测、执行中检测、执行后修复”的预测性状态一致性；用 HUT 人类对抗测试系统制造并标注状态分歧，把 temporal(5%)、softbody(8%)、human(20% 轴) 三个最弱项一起攻。**

### 4.2 五个组件

```text
┌────────────────────── Offline ──────────────────────┐
│ 33k 官方数据 + HUT 对抗数据                          │
│   ├─ POT-style object records（role slots, 3D, mask）│
│   ├─ Part-state labels（8 个软体/铰接任务）          │
│   ├─ Object Dynamics Head（ODH）：预测 M_{t+H}       │
│   └─ Divergence calibrator：per-task τ                │
└──────────────────────────────────────────────────────┘
                          │
┌────────────────────── Online（单一 checkpoint）──────┐
│ 4×RGB + proprio                                      │
│   → stereo depth → mask head（蒸馏）→ object records  │
│   → ODH 预测 M̂_{t+H}                                 │
│   → 执行 chunk → 观测 M_{t+H}                        │
│   → PSC 分歧分数 D = d(M̂, M) + relation/part mismatch │
│        ├─ D < τ_low：继续                             │
│        ├─ τ_low ≤ D < τ_high：减速/重观测/换视角      │
│        └─ D ≥ τ_high：回滚到 last consistent state    │
│                       → 重抓/重规划/放弃              │
│   → SSG 谓词确认 → SVL 放置闭环 → 任务推进            │
└──────────────────────────────────────────────────────┘
```

1. **POT-style object state（底座）**：role-indexed records、3D centroid/extent、visibility/confidence、relations；用双目替代 RGB-D；mask head 蒸馏。
2. **ODH（Object Dynamics Head）**：小 transformer/GNN，输入 `M_t` + action chunk + proprio，预测 `M_{t+H}` 的 centroid/extent/orientation/relations/part states；自监督训练，不需要额外标签。
3. **PSC scorer**：`D = ||M̂ - M||_Σ + λ_rel * relation_mismatch + λ_part * part_state_mismatch`；按任务/对象校准阈值；输出可解释的分项。
4. **Repair policy**：按分歧级别选择 re-observe / slow-down / rollback / regrasp / replan；有预算守卫（≤2 次重观测、≤1 次回滚/task）。
5. **HUT**：人类对抗测试，制造 D1/D2/D3 事件并标注；训练 ODH/repair，评估 held-out user/task/perturbation。

### 4.3 为什么不是“大 world model”

DreamZero 14B、7Hz、video diffusion，泛化约 2×，但算力和延迟都不适合 UniBot 的 180s/在线 API；GigaBrain 的世界模型生成数据也依赖 RGBD。PSC 的 ODH 只预测 **对象/部件的低维状态**，不生成视频：

- 输入 token 数 ≤ 8 objects × 33 features + action chunk；
- 模型 <50M 参数，推理 3–5ms；
- 训练数据就是 33k 演示的 object records，不需要 world-model 生成；
- 预测失败时退回 POT 谓词，不会比基线更差。

### 4.4 为什么不是“又一个 HITL”

官方计分不允许人在线接管；HUT 只在离线。PSC 的在线恢复是 **自主的**：分歧分数由模型自己算，恢复动作由策略自己出。HUT 的作用是：

- 提供“人在执行中改状态”的高密度数据（ADC 证据）；
- 提供分歧事件的标签（POT 没有）；
- 提供 held-out user 的泛化测试（SocialVLA/ADC 没有）。

## 5. 可验证性：四个假设与淘汰线

### H1：PSC 能在任务失败前检测到人为状态分歧

- 指标：分歧事件检测 AUROC/AP；time-to-detect（扰动时刻 → 首次 D>τ）。
- 目标：AUROC ≥ 0.80；中位 time-to-detect ≤ 0.5s；误报率 ≤ 10%。
- 对照：POT 事后谓词（只能在 chunk 后）、VLA-Corrector 的 learned verifier、随机分数。
- 淘汰线：AUROC < 0.70 或误报 >20% → 不做在线触发，只做离线诊断。

### H2：PSC 触发的修复比“谓词失败后修复”更省、更成功

- 指标：任务成功率、恢复成功率、恢复时间、无效动作数、180s 超时率。
- 目标：在 8 个 pilot 任务上，恢复成功率 +10pp，恢复时间 −30%，整体成功率 +5pp。
- 对照：POT + predicate-only recovery；POT + 固定重试；无恢复。
- 淘汰线：恢复成功率 <+5pp 或整体成功率 <+2pp → 回退到 POT + HUT 数据（只做数据增益）。

### H3：收益集中在 temporal/softbody/human，而不是 simple-pick

- 指标：按 RoboChallenge tag 分组的 SR；UniBot 5 轴 SR；per-task SR 方差；无零任务比例。
- 目标：temporal/softbody/human 三组 +8~15pp；simple-pick 不下降 >2pp。
- 若所有 tag 均匀提升 → 说明只是更好的 encoder，不是状态层；需要补消融。
- 淘汰线：hard tags <+2pp → 主判断不成立，转“部件状态 + HUT 数据”二线。

### H4：HUT 训练的检测器能泛化到未见用户/任务/扰动

- 指标：held-out user/task/perturbation 的 AUROC、恢复成功率。
- 目标：下降 ≤10pp；不能只在训练用户上有效。
- 对照：只在官方备注剧本上训练；只在仿真扰动上训练。
- 淘汰线：held-out 下降 >20pp → HUT 过拟合，需要更多用户/任务。

### 5.1 实验矩阵

| 编号 | 系统 | 目的 |
|---|---|---|
| E0 | POT-VLA baseline（或 GPR-VLA + POT records） | 基线 |
| E1 | E0 + 双目 depth（替代 RGB-D） | 感知等价性 |
| E2 | E1 + ODH（只预测，不触发） | 预测质量 |
| E3 | E2 + PSC 检测（只报警，不修复） | 检测 AUROC/误报 |
| E4 | E3 + repair policy | 恢复/任务 SR |
| E5 | E4 + HUT 数据 | 人类扰动泛化 |
| E6 | E5 + part-state graph（8 个软体/铰接任务） | 软体增益 |
| E7 | E5 + SSG/PGL/OPT/SVL 完整栈 | 与上一轮组件合体 |

消融：预测 horizon H ∈ {1,4,8,16}；τ 分位数；ODH 输入有无 action；object vs part；HUT vs 官方备注；检测器输入有无 uncertainty；重观测策略（固定 vs 主动）。

### 5.2 统计与预算

- 官方计分：32 任务 × 10 次 = 320 episodes；整体成功率二项标准误约 2.6pp（p=0.3），paired bootstrap 可检测 3–5pp。
- HUT：full 8 任务 × 5 轴 × 2 × 3 用户 = 240 episodes；pilot 4 任务 × 5 × 2 × 2 = 80 做 smoke。
- 离线：mask pseudo-label 165k 关键帧；ODH 33k episodes；策略 LoRA 2–3 周（8×H100）。
- 在线：mask 10–15ms + stereo 10–20ms + ODH 3–5ms + policy 60–100ms ≈ 100–150ms/chunk；p99 目标 <200ms。
- 调试槽：T27（叠放）、T10（插入）、T19（拉链）、T24（动态/人扰）、T16（软体）；每次大版本 1 槽。

### 1.5 数据与双目标定

- 32 个 HF 数据集，约 **33,276 episodes / 169h**；HangCup **1,043 episodes、194,564 帧、30fps**，`lastModified=2026-10-14`（[S9][S10]）。

### 1.6 API 与单模型约束

- 观测：4×RGB、双臂关节/EE 位姿、夹爪、下半身、`observation.language` 单字符串。

### 1.7 POT 的关键细节

- 验证：chunk 执行后刷新 `M_{t+H}`，几何谓词成立才推进；失败触发 re-observe/re-ground/retry/replan。
- 限制：object-record quality、SAM3/RGB-D reliability、camera calibration、action-expert embodiment coverage；future work 明确列出 **active multi-view memory、richer contact、dexterity、human interaction**。

## 2. 评分算术：从“步骤分大头”改为“整任务成功 + 跨轴状态”

### 2.1 目标函数

```text
SR_t   = (1/10) Σ_{r=1..10} success(t, r)          # 每任务 10 次
Rank   = sort by (1/32) Σ_t SR_t                    # 成功率优先
Tie    = sort by (1/32) Σ_t StepScore_t             # 步骤分 tie-break
Then   = earlier submission
```

因此：

- 每个任务权重 **1/32**；每个 trial 权重 **1/320**。
- 5 个泛化轴在全局各占 **20%**（每任务每轴 2/10）；单轴改造的天花板是 20%。
- 跨轴的状态层（对象/部件状态）比单轴数据增强更划算，但它必须真的跨轴，而不是只在位置轴上有效。

### 2.2 320 episodes 的统计分辨率

- p≈0.3 时，320 trials 的二项标准误约 **2.6pp**；10 次/任务的单任务分辨率是 10pp。
- 因此：**不要用单任务 10 次的结果判断 +2pp**；用 32 任务聚合 + paired bootstrap。
- 目标增益：整体 +5pp 需要约 8 个任务 +10pp，或 16 个任务 +5pp；这比“单任务 +20pp”更现实。
- “无零任务”比例是一个有用的 breadth 指标：32 任务中至少成功 1 次的任务数。

### 2.3 步骤分只做 tie-break 与诊断

- 不再按“终局放置 ~60% 步骤分”分配预算。
- 步骤分用于：
  1. 成功率相同时的 tie-break；
  2. 诊断“卡在哪一步”（例如 T16 第 2/5 步、T31 拉链第 3/3 步）；
  3. 恢复策略的中间奖励（离线训练），但不是在线主目标。
- 若成功率已经很高（>50%），再优化步骤分才有边际价值；UniBot 目前 top <30%，先保成功。

### 2.4 180 秒预算

- 演示中位数约 6–10s/任务；180s 足够 1–3 次重观测/回滚，但长程任务（T16/T17/T31）要限次数。
- PSC 预算：≤2 次 L1（减速/重观测），≤1 次 L2（回滚），总恢复时间 ≤20s/task；超过则 abort 当前子任务，回 SSG 上一稳定步。
- 推理预算：mask 10–15ms + stereo 10–20ms + ODH 3–5ms + policy 60–100ms ≈ 100–150ms/chunk；p99 <200ms。

## 3. 失败模型：状态分歧的三个时间点

### 3.1 定义

```text
t:        当前 object memory M_t
t+H:      一个 action chunk 执行完
M_t^act:  策略用来条件化动作的状态
M_t^ver:  验证器用来判断完成的状态
D_t:      预测状态 M̂_{t+H} 与观测状态 M_{t+H} 的分歧
```

POT 的核心失败模式是 `M^act` 与 `M^ver` 不一致；PSC 进一步区分：

- **预测分歧**：`d(M̂_{t+H}, M_{t+H})` 大；
- **表示分歧**：`d(M_t^act, M_t^ver)` 大；
- **语义分歧**：谓词/角色/部件状态不一致。

### 3.2 D1/D2/D3

| 类型 | 触发 | UniBot 例子 | POT 事后谓词 | PSC |
|---|---|---|---|---|
| D1 外力改状态 | 人移动/拿走/撤销/放回 | T27 叠第二个后拿走；T19 拉上后拉开；T14 拧回瓶盖；T24 把可乐放回起点 | chunk 后才发现 | 预测 `M_{t+H}` 与观测比对，提前减速/重观测/回滚 |
| D2 内部状态变化 | 软体/铰接/液体 | T16 毛巾折角滑落；T19 拉链只咬合一半；T31 笔袋没闭合；T32 针管回吸 | 对象级谓词太粗，易 false success | 部件状态图 + 预测误差 |
| D3 身份/角色错配 | 干扰物/未见物/遮挡/换容器 | 抓错杯子；把干扰物当目标；容器被换 | role slot 可部分处理 | 预测角色/关系，检测 ID switch |

### 3.3 为什么“预测”是必要的

- 事后谓词只能在 chunk 边界检查；chunk=16、5–10Hz 时，检查间隔 1.6–3.2s。
- 人为扰动在 chunk 中间发生时，策略会继续执行错误动作；越晚发现，越难回滚。
- 软体/铰接的几何谓词难写；学习到的部件状态预测可以给连续分数。
- 预测不是替代谓词：谓词负责“确认”，预测负责“预警”；两者一致才推进。

## 4. POT-PSC 架构

### 4.1 总览

```text
Offline
  33k UniBot episodes
    ├─ SAM2/MobileSAM2 teacher → class-agnostic masks → distill mask head
    ├─ stereo calibration → metric depth → object records
    ├─ object/part state labels (geometry + human keyframes)
    ├─ ODH training: (M_t, action chunk) → M̂_{t+H}
    └─ HUT: human adversarial episodes → divergence labels / recovery data
                          │
Online（single checkpoint）
  4×RGB + proprio
    → stereo depth (head) + wrist close-up
    → mask head (distilled) + tracker → M_t
    → ODH → M̂_{t+H} (multi-horizon)
    → policy → action chunk
    → execute; observe M_{t+H}
    → PSC: D = d(M̂, M) + relation/part mismatch + uncertainty
         ├─ D < τ_low: continue
         ├─ τ_low ≤ D < τ_high: slow / re-observe / change view
         └─ D ≥ τ_high: rollback to last consistent; regrasp/replan/abort
    → SSG predicate confirm → SVL settle-verify → next step
```

### 4.2 Object state schema

```text
Record r_i = {
  id: persistent int,
  role: TARGET | DESTINATION | SUPPORT | TOOL | HANDOVER_PARTNER | DISTRACTOR | UNKNOWN,
  phrase: str,
  mask: 480×640 bool,
  bbox: [x1,y1,x2,y2],
  centroid_base: [x,y,z] (m),
  extent: [dx,dy,dz] (m),
  orientation: 6D (optional),
  visibility: [0,1],
  confidence: [0,1],
  last_seen: frame_id,
  velocity: [vx,vy,vz],
  relations: {
    on: id?, in: id?, near: id?, supported_by: id?,
    contained_by: id?, stacked_on: id?, attached_to: id?, aligned_with: id?
  },
  part_states: {
    open: bool?, closed: bool?, folded: bool?, zipped: bool?,
    upright: bool?, full: bool?, inserted: bool?, attached: bool?
  },
  provenance: {camera, frame, mask_source, depth_source}
}
```

- K=12 slots（POT 默认 8；UniBot 32 任务角色更多，12 足够；超过则按 confidence/role 裁剪）。
- 所有几何量在 **base frame**；容器系位姿单独存 `T_base_container`，供 PGL/OPT 使用。
- 每个 record 有 `last_consistent` 快照，用于回滚。

### 4.3 双目 + mask 蒸馏

**StereoPOT**：

1. 头戴双目已矫正；用 SGBM/RAFT-Stereo 计算视差；左右一致性 + 置信度过滤。
2. `Z = f*B/d`；反投影到 base frame；工作区裁剪（桌面 ±0.6m，高 0–0.5m）。
3. 与对象 mask 融合：mask 内深度取稳健分位数（中位/20th），得到 centroid/extent；透明/反光物体用 wrist 近景 + 多帧融合。
4. 跟踪：mask IoU + 3D centroid 距离 + DINO feature；Hungarian 匹配；遮挡时保留 slot，visibility 降低；重新出现时用 feature + 空间先验 re-ID。
5. 失败回退：双目视差 <阈值（远处/无纹理）→ 单目尺度先验 + wrist 近景；仍失败 → 保留 uncertain slot，触发主动重观测。

**Mask head**：

- query-based decoder，接在共享视觉 backbone 上；输出 K 个 class-agnostic masks + objectness + feature。
- 离线 teacher：SAM2/MobileSAM2 在关键帧上生成 pseudo-labels；用 mask BCE + dice + temporal consistency + 3D consistency 蒸馏。
- 单 checkpoint：mask head、state encoder、ODH、policy 同一个模型；推理不调用 SAM2。

### 4.4 ODH：对象动力学头

**输入**：

- object tokens：K×F（role embedding + pose + extent + visibility + confidence + relations + part states）；
- action chunk：H×A（EE/joint delta + gripper）；
- proprio：双臂关节/EE、夹爪、下半身；
- optional：language embedding、SSG step embedding、time。

**结构**：

- 4 层 transformer，role/relation attention；action token 与 object token cross-attend；
- 输出多头：
  - `Δcentroid`、`Δextent`、`Δorientation`（6D）；
  - relation logits（on/in/near/...）；
  - part-state logits（open/closed/zipped/folded/...）；
  - uncertainty（heteroscedastic variance）；
- 多 horizon：h=1,2,4,8,16；每个 horizon 一个轻量 head；主输出 h=H（chunk 末），中间 horizon 用于早期预警。

**训练**：

- 自监督：用演示的 `M_t`、action chunk、`M_{t+H}`；不需要额外标签；relation/part 用几何/伪标签。
- 防 copy：随机 mask action 或 object token；加 action dropout；否则模型学会“抄当前状态”。
- 多任务共享：32 任务同一 ODH；task embedding 只作为可选条件，避免任务头。

### 4.5 PSC scorer

```text
D_pose  = Mahalanobis(centroid/extent/orientation; μ_task, Σ_task)
D_rel   = 1 - mean(relation logits agree)
D_part  = BCE/KL(part states)
D_unc   = mean(predicted variance)
D       = w_p*D_pose + w_r*D_rel + w_s*D_part + w_u*D_unc
```

- 归一化：按任务/对象统计；避免大物体支配。
- 阈值：`τ_low` = clean 数据的 95th percentile；`τ_high` = 99th percentile 或 HUT 的高分位；按任务校准，但共享先验。
- 时间平滑：EMA + 2 帧连续超阈；避免单帧 mask 抖动误报。
- 解释：输出 top-3 触发对象/关系/部件；写日志，便于调试槽分析。
- 冷启动：前 5 帧只积累，不触发；用初始观测建 `last_consistent`。

### 4.6 Repair policy

| 级别 | 触发 | 动作 | 预算 |
|---|---|---|---|
| L0 | D < τ_low | 继续 | — |
| L1 | τ_low ≤ D < τ_high | 减速 0.5×；头/腕重观测；重算 ODH | ≤2 次/task |
| L2 | D ≥ τ_high，或谓词失败 | 回滚到 last consistent；重抓/重规划 | ≤1 次/task |
| L3 | L2 后仍失败，或 180s 将尽 | abort 子任务；回 SSG 上一稳定步；保守提交 | 1 次/task |

- 先规则后学习：L1/L2/L3 的阈值和动作先用手工规则；用 HUT 数据训练一个轻量选择器（输入 D 分项、对象/部件、剩余时间、历史），目标是恢复成功率/时间。
- 防振荡：滞回 + 最小 dwell 时间；同一对象 2s 内不重复回滚。
- 与 SVL 接口：SVL 负责落点 settle；PSC 负责早期预警；两者不重复触发。

### 4.7 SSG/PGL/OPT/SVL 的接线

- **SSG**：从 `score_steps` 编译任务图；每个 step 有 pre/post predicate；PSC 预测 `M̂_{t+H}` 是否满足下一步 pre；不满足则提前重观测。
- **PGL**：容器/目标 mask + 双目 → 2D 锚点 → 6D 目标；PSC 预测放置后的关系（in/on/stacked），分歧大则重新选目标。
- **OPT**：K 条演示的容器系释放位姿中位数 + 离散度；PSC 检测容器是否被移动（`T_base_container` 分歧），若移动则重算容器系，而不是沿用旧位姿。
- **SVL**：缓放→静置→稳定性/谓词校验；PSC 提前触发减速，SVL 做最终确认；失败时按预算 nudge/regrasp/retry。
- **ICR**：降级为“恢复段检索”（从 HUT/演示中检索相似分歧的恢复轨迹）；不作为主路径。

### 4.8 PSC-Part：软体/铰接的部件状态图

仅对 8 个任务开启：T03、T14、T16、T18、T19、T23、T28、T31（可加 T17/T29）。

**部件词表**：

```text
cloth_corner, cloth_edge, cloth_center,
zipper_slider, zipper_teeth, zipper_pull,
bag_opening, bag_body, bag_handle,
lid_hinge, lid_rim, container_rim,
cable_end, cable_body, handle, button, piston
```

**部件图**：

- 节点：部件 mask/点云/质心/朝向/可见性；
- 边：物理连接（缝线、拉链齿、hinge、开口）；
- 状态：open/closed、folded/unfolded、zipped/unzipped、upright/fallen、attached/detached、full/empty、inserted/removed；
- 谓词：`zipper_closed(slider, teeth)`、`towel_folded(corner_i, corner_j)`、`bag_upright(opening)`、`lid_closed(hinge)`、`liquid_level`。

**感知**：

- 离线：SAM2 video masks + 人工关键帧标签；RoboSeg/UniPart 可作为部件 prompt/分割先验（[S34][S35]）。
- 在线：部件 head 蒸馏进同一 checkpoint；跟踪用 mask IoU + 部件 keypoint；置信度低时退回对象级 PSC + SSG phase。
- 训练：部件 mask BCE/dice + 状态 CE/BCE + 时序一致性；ODH 增加 part-state 输出。

**风险**：布料/拉链标注贵、遮挡严重、部件跟踪漂移；因此 PSC-Part 是二线，先在 T16/T19 两个任务验证，不阻塞主线。

### 4.9 单 checkpoint 合规

- 唯一学习模型：mask head + state encoder + ODH + policy + repair selector 都在同一个 checkpoint/权重文件。
- 确定性代码：SSG/PGL/OPT/SVL/PSC scorer/预算守卫；不是“第二个模型”。
- 离线 teacher：SAM2/MobileSAM2 只生成 pseudo-labels，不参与推理；模型卡写明。
- 检索库：HUT/恢复段是数据，不是模型；模型卡披露。
- 外部数据：默认 OFF；L2L/HUT 数据在规则确认后并入；若禁止，HUT 只做评估。

## 5. 训练配方

### 5.1 数据

### 5.4 计算与延迟

- 离线 mask pseudo-label：约 16.6 万关键帧（33k×5）；8×H100，2–3 天。
- ODH：33k episodes 的 records；<50M 参数；8×H100，1–2 天。
- 策略：GPR-VLA/WLA-1.0-Base（6B）LoRA/action expert；8×H100，2–3 周。
- HUT：240 episodes；2 名操作员 + 1 名评估者；2–3 周（含标注）。
- 推理：单卡 L40/4090 目标；mask 10–15ms、stereo 10–20ms、ODH 3–5ms、policy 60–100ms；p99 <200ms。
- 存储：object records 每 episode ~1–5MB；HUT 视频/标注 ~1TB。

### 5.5 快速胜利（不阻塞主线）

1. **idle-frame/phase-balanced 采样**：按动作幅度/阶段重采样，降低 idle 帧梯度主导；成本低，可能直接 +1–3pp。
2. **双目 depth 替换**：如果基线用单目，先加双目，作为 E1 的干净消融。
3. **官方 human notes 回放**：不采 HUT 也能先用 T27/T19/T14 的备注做 scripted perturbation，验证 PSC 检测。
4. **SSG 谓词校验**：先把 32 任务的 step predicate 写全，作为 PSC 的监督/验证骨架。

## 6. 伪代码

```python
class POTPSC:
    def reset(self, task_spec, obs):
        self.ssg = compile_ssg(task_spec)
        self.M = init_object_records(obs)
        self.last_consistent = snapshot(self.M)
        self.budget = Budget(reobserve=2, rollback=1, recover_s=20)
        self.history = []

    def act(self, obs):
        depth = stereo_depth(obs.head_left, obs.head_right)
        masks = self.mask_head(obs.images)
        self.M = self.tracker.update(self.M, masks, depth, obs.proprio)

        M_hat = self.odh.predict(
            self.M, self.prev_chunk, obs.proprio,
            horizons=[1, 2, 4, 8, 16]
        )
        D, parts = self.psc.score(M_hat, self.M)

        if D >= self.tau_high and self.budget.can_rollback():
            self.budget.use_rollback()
            self.M = restore(self.last_consistent)
            self.ssg.rollback_to_stable()
            return self.repair.regrasp_or_replan(self.M, parts)

        if D >= self.tau_low and self.budget.can_reobserve():
            self.budget.use_reobserve()
            return self.repair.slow_reobserve(self.M, parts)

        chunk = self.policy.act(obs, self.M, self.ssg.current)
        self.prev_chunk = chunk
        self.pending = (M_hat, chunk)
        return chunk

    def after_chunk(self, obs):
        depth = stereo_depth(obs.head_left, obs.head_right)
        masks = self.mask_head(obs.images)
        self.M = self.tracker.update(self.M, masks, depth, obs.proprio)

        if self.ssg.predicate_holds(self.M):
            self.last_consistent = snapshot(self.M)
            self.ssg.advance()
        else:
            self.repair.trigger_predicate_failure(self.M)

        self.history.append((self.M, self.ssg.current, self.psc.last_D))
```

```python
def train_odh(dataset):
    for batch in dataset:
        M_t, action, M_next, proprio = batch
        M_hat, var = model.odh(M_t, action, proprio)
        loss = gaussian_nll(M_hat.pose, M_next.pose, var)
        loss += ce(M_hat.relations, M_next.relations)
        loss += bce(M_hat.parts, M_next.parts)
        loss += consistency(M_hat, M_t)
        loss.backward()
```

def hut_episode(robot, task, user, perturbation):
    obs = robot.reset(task)
    while not done:
        action = policy.act(obs)
        if perturbation.due():
            user.apply(task, perturbation)
        obs = robot.step(action)
        labels.append({
            "t": robot.time,
            "perturbation": perturbation,
            "M_before": policy.M,
            "M_after": policy.observe(obs),
            "D": policy.psc.last_D,
            "recovery": policy.repair.history,
        })
