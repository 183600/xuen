# 第 8 轮 · STAR-GPR：状态隔离是架构，语言是契约，地形是接触面

> 检索/复核日期：2026-10-27（UTC）。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API。本轮三个灵感词是「状态隔离」「自然语言指令」「地形适应」。我先用中文参赛手册全文把四个此前含混的事实钉死，再把三个词分别落到评测协议、任务结构和接触几何上，最后合成主判断：**头部<30% 更可能不是“看不见”，而是“记不住状态、完不成最后一下接触、换台机器人就偏了”；把状态隔离从部署要求提升为第一性架构，用语言编译出可验证的接触契约，用立体支撑地形参数化接触，再用官方人类干扰剧本做保守恢复——这是一次改动同时打成功率、干扰轴和跨机器人隐藏轴的杠杆。**

## 0. 先把四个事实纠正过来

### 0.1 排名：成功率是主指标，步骤分只是 tie-break，提交时间再次

中文手册 4.3.2 原文：「最终排名依次依据：总平均成功率 > 总平均步骤分 > 提交时间。」4.3.3 还规定多次完整计分评测取「总平均成功率最高的一次」，成功率相同取步骤分最高，仍相同取提交时间最早。上一轮写的“成功率与步骤分综合排序”不准确，必须改成：**先赢成功率，再谈步骤分；步骤分只在成功率打平时决定名次。** 这会直接改变预算：任何“提高部分分但可能降低全任务成功率”的技巧都不该进主路径。

### 0.2 10 次运行是 5 类 ×2 的组合，不是五个独立轴

手册 2.1：每个任务 10 次独立运行，5 种泛化类型各出现 2 次——位置、干扰物、桌面背景、未见物品、人为干扰。上一轮把“五轴”当成可分层归因的独立维度，做了“单轴 +Δ = Δ/5”的算术；**这个算术不成立**，因为每次运行是多种泛化设定的组合，轴的边际效应是混叠的。正确的说法是：终局接触在 10 次运行里都会出现，所以它仍是跨组合的公共因子；但不能再把某次失败干净地归因给单一轴。

更关键的新事实（5.1）：**同一任务的不同泛化场景在同一台真机上评测**；不同任务在每次测评中随机分布在各台物理机器人上；同一泛化场景在多次测试中也可能分配到不同机器人。于是“跨机器人”不是第六个泛化轴，而是**隐藏的标定/几何 nuisance**：同一任务的 10 次运行共享一台机器人，但 32 个任务之间可能换机器人；跨提交更不保证同一台。对策不是“再补一个泛化轴”，而是**每端口在线标定 + 规范桌面坐标系**。

### 0.3 每天只有 1 个测试时段，计分与调试共用；计分必须全 32 任务

手册 3.3：「每支队伍每日仅可预约一个测试时段」；3.4：计分测试（Multitasks）单次提测须包含同一机型的全部 32 个任务；单任务调试不计分。上一轮“调试槽 + 少量计分跑”的计划过乐观——**没有独立的调试槽和计分槽**，一天只有一次真机机会。因此真机必须当“发布门”而不是“调参器”：大部分迭代在本地 mock/离线回放，真机只验证里程碑；每次真机优先跑完整 32 任务计分（数据量最大、且计入 best submission），单任务调试只用于定位致命接口/安全问题。

### 0.4 N 端口/状态隔离是硬要求；隐藏着跨机器人轴

手册 3.5.3：评测在 N 台 G1 上随机分配任务，N 未公布（示例 N=5）；每台机器人固定一个端口，选手暴露从 8765 起的 N 个连续端口；多端口共用模型时：「不同端口可能被同时调用」「每个端口对应一台独立机器人的独立任务，各端口的 reset 与历史状态须严格隔离，不可串用。」这不是建议，是评测协议。它带来两个设计约束：

- **并发安全**：共享后端必须能同时处理多端口请求，不能互相阻塞；
- **状态隔离**：任何跨端口/跨 episode 的可变状态都是 bug，甚至可能被判定为串用。

同时，5.1 的机器人分配规则意味着：**同一任务同一台机，任务之间换机，跨测试换机**。所以“每端口在线标定”既符合协议，也正好打隐藏轴。

### 0.5 榜单仍是占位，“榜首<30%”只能当工作假设

截至 2026-10-27，`leaderboard.html` 仍是 Coming Soon；`leaderboard_data.json` 仍是 `generated_from: gen_leaderboard.py` 的 8 个占位模型，榜首 MolmoAct2 29.7% 成功率 / 39.0 步骤分。**“榜首成功率也不到 30%”目前只能作为你的工作假设，不能当作真实榜单证据。** 但假设本身值得认真对待：如果真实头部 <30%，最可能的解释不是“语义看不懂”，而是成功率闸门 + 长程组合 + 最后一下接触 + 干扰 + 隐藏标定；这正好是下面要拆的结构。若真实头部其实 >30%，这套分析仍成立，只是边际收益变小；若真实头部 <20%，说明状态/接触问题更严重，STAR-GPR 更值得押。

### 0.6 数据/接口：33k、四路相机、有立体标定，但 API 不给相机参数

- HF collection 32 个数据集；上一轮逐数据集 `info.json` 汇总 **33,276 episodes**（本轮复核 collection 仍是 32 items；HTTP 567 风控导致未能逐文件重抓，标“沿用上轮汇总”）。HangCup 1,043 条 / 194,564 帧 / 30fps，`lastModified=2026-10-14`。[S8][S9]
- 数据集 `meta/info.json` 的 `camera_params.head_stereo` 给出左右内参、畸变、R、T，基线约 **58.25 mm**，`rectified: true`；wrist_left/right 也有 color/IR 内参。**这是离线标定/合成数据的资产，不是在线 API 的字段。**
- API 观测只有：4 路 RGB（480×640）、双臂关节、左右 EE 位姿（base 系 xyz+rpy）、夹爪开度、`lower_body[15]`（含 waist）、`language`；**没有 camera_params、没有 state_torso/state_d435、没有关节力矩/力/触觉**。[S7]
- 数据集动作里 `pivot` 几乎固定（std≈0.007），主动底座/行走是 OOD；官方也没有地形/行走赛道。所以「地形适应」必须解释成**桌面支撑/接触地形**，不能解释成 locomotion。[S9]
- 每条任务 5 条英文复述存在 `meta/tasks.parquet`（`@` 分隔），32×5=160 条；这是语言分支的天然验证集。[S9]

## 1. 三个灵感词，各自钉到事实上

### 1.1 状态隔离：不是工程杂务，是评测协议里唯一同时约束任务、机器人、时间和干扰的维度

官方要求是“端口级隔离”。但真正决定成败的是**时间上的状态**：任务做到哪一步、哪个物体被抓起/放下、支撑面在哪、人把什么移动了/撤销了。一个无记忆的 VLA 在人为干扰后，最常见的失败不是“不会抓”，而是：

- 不知道刚才已经完成了什么，重复做/漏做；
- 不知道人把物体移走了/把拉链拉开了/把叠好的碗拿走了，继续按旧计划执行；
- 不知道当前机器人/桌面的几何，沿用上一台机器人的标定。

所以我把状态分成四层作用域，并把“隔离”写成不变量：

| 作用域 | 内容 | 生命周期 | 隔离规则 |
|---|---|---|---|
| PortScope | 机器人 id、桌面/相机标定、端口计数器 | 跨 episode 保留（同一端口同一机器人） | 端口间绝不共享；大幅标定漂移时失效重建 |
| EpisodeScope | 任务程序、当前步骤、物体状态、支撑图、干扰日志、历史 | 每次 `reset()` 清空 | 绝不跨 episode 复用；reset 只清这一层 |
| TaskScope | 32 个任务程序、160 条复述、评分步骤、官方干扰剧本 | 只读 | 全局共享只读 |
| ModelScope | 权重、tokenizer、检索索引 | 只读 | 全局共享只读；推理期不改权重 |

不变量：

1. 所有可变状态必须在 StateStore 里，禁止模块级全局变量；
2. 每次读写带 `(port, episode_id)`，跨端口读直接报错；
3. `reset(port)` 只清 EpisodeScope，不碰 PortScope，不碰其他端口；
4. 模型权重只读；推理期不做任何任务特定微调；
5. 每次状态转移写审计日志，可回放、可检查。

这听起来像工程，但它带来一个可证伪的研究问题：**显式、隔离、可验证的状态，是否比无记忆 VLA 在人为干扰和跨机器人换机下显著提高全任务成功率？** Chameleon 已经把“记忆是策略问题”说清楚：历史要可分（separability）、可寻址（addressability）、可前瞻（prospectiveness）[S13]；我们的四层作用域就是把这三点落到评测协议上。RESCUE 则提醒：运行时监控不是越灵敏越好，在 stop-and-reset 模型下，即使理想检测器也只能承受 2.0–3.3% 的误报，否则不必要的重置会吃掉收益[S24]。所以 IMR 的设计原则是**保守干预、优先继续、只在状态被证伪时重规划**，不是“一有异常就停”。

### 1.2 自然语言指令：不是 prompt，是契约

数据集每个任务有 5 条英文复述；评测很可能在这些复述里采样，也可能用未见物品/未见组合。语言分支要解决的不是“把句子编码进模型”这么简单，而是三件事：

1. **指代**：哪个物体、哪个容器、哪个序数（第二个碗、左边的杯子）、哪个空间关系（在架子上、在盒子里、颜色匹配）；
2. **步骤**：这句话对应任务的哪一步、这一步的 pre/post condition 是什么；
3. **验证**：做完没有？成功谓词是什么？

我的做法是**离线编译、在线匹配**：

- 离线：把官方 `score_steps`、任务描述、5 条复述、人类干扰备注，编译成 32 个 `TaskProgram`（JSON）：步骤、权重、角色、pre/post、接触契约、成功谓词、干扰剧本；
- 在线：用 VLA 的文本编码器把当前 instruction 与 160 条复述匹配，选中程序；把当前步骤的 instruction + 结构化状态渲染成短 prompt，喂给同一个 VLA；
- 验证：每步用几何/视觉谓词检查 postcondition；成功谓词是程序的逻辑组合，不是学习出来的 reward。

这把语言变成了**可验证的契约**：语言负责“要什么”，程序负责“怎么算完成”，VLA 负责“怎么做”。RefGuard 的证据支持“指代要延迟承诺”：在重复物体/歧义锚点/帧依赖空间词下，联合推断 target-anchor-frame 比早承诺稳得多，90% 歧义压力测试正确执行[S14]；FineART 的证据支持“子任务预测”对空间指令和未见长程的巨大增益（32→100%、16→76%）[S15]。我们不一定要加子任务头；把程序里的当前步骤作为 prompt，就是最便宜的子任务条件化。

单模型合规：**推理期不调用外部 LLM/VLM**。程序编译器是确定性的；如果离线用 LLM 辅助作者任务程序，必须在模型卡里披露，且推理期不依赖它。160 条复述的匹配用 VLA 自己的文本编码器，不引入第二个模型。

T26 的契约示例：

```json
{"type":"insert","object":"cable","target":"port","axis":"port_normal",
 "pre":{"offset":[0,0,0.03],"tol":0.005},
 "insert":{"depth":0.012,"search":"spiral","radius":0.004,"speed":0.01},
 "verify":["visual_seat","cable_slack"],"retry":{"max":2}}
```

T27 的契约示例：

```json
{"type":"stack","object":"bowl_3","target":"bowl_2","support":"bowl_2_rim",
 "release":{"height":0.003,"settle":0.5},"verify":["stable","centered"],"retry":{"max":1}}
```

这些不是自然语言，而是语言编译出来的、可执行可验证的接触契约。

### 1.3 地形适应：没有行走赛道，地形=桌面支撑面+接触面+视觉地形

官方没有地形/行走任务，`pivot` 几乎固定，主动底座运动是 OOD。所以「地形适应」在 UniBot 里唯一合理的解释是**桌面接触地形**：

- **支撑地形**：桌面高度/倾斜/摩擦、架子层板、盒底、杯口、堆叠面、传送带、布料；
- **接触地形**：插孔/网口/充电座、拉链/铰链/锁/瓶盖、试管架槽位、相框支架；
- **视觉地形**：桌布颜色/纹理、光照、背景杂物。

数据集的 head stereo 已标定（基线 58.25mm，rectified），API 又给了四路 RGB 和 EE 位姿。我们可以：

1. 用 head stereo 做局部点云/高度图/法向/支撑区域/障碍图；用 RANSAC 估桌面平面；
2. 用 wrist camera 做近距对齐/插入/闭合的视觉伺服；
3. 从演示数据离线标定 head/wrist 到 EE/base 的外参（CalibAll 式），在线用桌面平面和 EE 位姿细化；如果外参不可得，就用**相机系/相对动作**（OC-VLA++/IronMind 的思路）降低对标定的依赖；
4. 把接触参数化成四类模板：`PLACE`（释放高度/姿态/稳定性/沉降）、`INSERT`（轴/预插/螺旋搜索/深度/seat 验证）、`CLOSE`（铰链/拉链方向/终点）、`STACK`（中心/支撑面/稳定性）。

Placeability 用部分点云做 6D 放置稳定性/可抓性，正好支撑 `PLACE` 的稳定性判据[S16]；VFAL 用视觉+力做可移动孔插入，但 G1 API 没有力传感器，我们只能借它的“视觉预插 + 柔顺搜索 + 失败恢复”结构，用视觉/本体替代力[S17]；StereoPatch 说明立体 RGB-D 融合对操作有增益[S23]；AOMGen/SMART 说明 articulated 物体的合成数据可以显著提升 VLA[S19][S20]。这些证据不要求我们造新模型，只要求把几何/接触显式化。

最关键的是**每端口在线标定**：同一任务的 10 次运行在同一台真机，不同任务可能换机，跨测试更可能换机。所以在每个端口第一次 `reset` 时估一次桌面/相机标定，存进 PortScope；后续 episode 复用并校验；标定残差大就重建。这样既满足“reset 与历史状态隔离”，又把隐藏的跨机器人轴变成可处理的几何问题。

## 2. 本轮主判断：头部<30% 的失败结构，和为什么是 STAR-GPR

### 2.1 先把失败算术写清楚

成功率是 32 任务 ×10 次的平均，每个任务要求**所有步骤完成**。假设一个任务有 k 步，单步成功率 p，则任务成功率≈p^k：

- p=0.8, k=3 → 51%; k=5 → 33%;
- p=0.7, k=3 → 34%; k=5 → 17%;
- 若最后一步接触成功率只有 0.5，前面 0.9：k=3 → 40.5%; k=5 → 32.8%。

32 个任务里 2–5 步，终局步骤合计 39.8% 权重；只要终局接触在相当一部分 episode 里失败，整体 <30% 完全不需要“感知崩溃”来解释。占位榜的步骤分比成功率高约 9pp，也指向“大部分步骤做完了、倒在最后一下/最后几步”。这给出一个可检验的杠杆：**终局接触 +Δ，会以“到达终局的比例 q”放大为整体成功率的提升**；q 用离线/真机测，不再拍脑袋除以 5。

### 2.2 头部路线对比：为什么“结构”可能胜过“规模”

| 路线 | 代表 | 强项 | 在 UniBot 的软肋 |
|---|---|---|---|
| 端到端 VLA | π0.5、GR00T N1.5、WALL-OSS、MolmoAct、Spirit | 语义泛化、实现简单 | 无记忆、接触精度弱、无状态隔离、换机偏 |
| 世界模型/混合 | DreamZero、DM0、WMA-0 | 接触预测、规划 | 慢、数据饥渴、状态漂移、难验证 |
| Harness/executive | Harness VLA | 冻结 VLA + 固定原语 + 记忆；扰动下 +38.6/25.4pp | 通用、非官方结构；planner 可能是外部 LLM；无端口隔离/度量地形 |
| 专家集成 | 每任务一个策略 | 单任务强 | **规则不允许**（必须单模型全 32 任务） |
| 数据/算力 scaling | 大通用模型 | 可能真的最强 | 不是小团队的优势；33k 官方数据也不支持无限 scaling |

Harness VLA 是离我们最近的先例：它把冻结 VLA 当作可重试的 contact-rich primitive，用固定解析原语做 grounding/staging/transport/release，再用记忆增强的 planner 组合；在 LIBERO-Pro/RoboCasa365 上比最强基线高 38.6/25.4pp，且不微调 VLA[S11]。这证明“VLA 只做接触段、外层做状态/原语”的路线可行。但它是通用框架，不知道 UniBot 的 32 个评分步骤、5 条复述、官方人类干扰剧本、每端口隔离和跨机器人换机；它的 planner 还可能是 LLM（单模型合规风险）。**我们的 delta 不是“也做一个 harness”，而是把 harness 做成官方的、确定性的、状态隔离的、带桌面接触地形的版本。**

### 2.3 为什么是 STAR-GPR：一次改动打三个东西

STAR-GPR = **S**tate-isolated **T**ask-program **A**daptive-contact **R**untime，跑在 GPR-VLA/WLA-1.0-Base 上。它的七个核心件：

1. **HVA（Harness 执行层，采用）**：冻结/微调的 VLA 只做 contact-rich 段；grounding/staging/transport/release/retry 用确定性原语；外层由任务程序驱动，不用外部 LLM。
2. **TPC（Task Program Compiler，升级 SSG/PGL）**：32×5 复述 + 官方 score_steps + 人类备注 → 类型化任务程序/接触契约/成功谓词。
3. **ESS（Episodic State Store，新增）**：Port/Episode/Task/Model 四层作用域；reset 清 episode；端口隔离；状态渲染成短 prompt；审计。
4. **LSG（Language-Scene Grounder，新增）**：属性/序数/空间关系/未见物体/歧义；target-anchor-frame；用 VLA 视觉编码器 + 几何聚类，不引入第二个检测模型。
5. **CFI（Canonical Frame Isolation，新增）**：桌面规范系、每端口在线标定、相机系/相对动作、跨机器人换机鲁棒。
6. **CTA（Contact Terrain Adapter，升级 SVL/OPT）**：head stereo 支撑图 + 四类接触模板（PLACE/INSERT/CLOSE/STACK）；视觉/本体验证；无力/触觉。
7. **IMR（Interference Monitor & Replanner，升级 NRB）**：官方人类干扰剧本 → 状态突变；保守触发；状态回滚/重规划；失败回放数据。

保留：GPR-VLA 主干、ICR 检索（可选）、TLE/ACP/GF 数据引擎、L2L 实验室数据（合规开关）、DebugLoop/真机发布门、AH-TP/Endurance/Compliance 安全件。

降级：TCLB 只做离线相对比较；FLEET 只做工程检查单；WMA-0 不进主路径；每任务 LoRA 砍；全 32 任务高保真孪生砍；自由仿真数据砍；运行时仿真/MPC 砍；触觉/力控砍（没有传感器）。

### 2.4 与第 7 轮 PILOT-GPR 的关系

- **保留**：终局放置是闸门/大头的判断；GPR-VLA；SSG 的评分步骤骨架；PGL 的“槽位→锚点→位姿”阶梯；OPT 的少样本位姿迁移；SVL 的 settle 闭环；NRB 的官方备注恢复；ICR 的检索；L2L 的数据协议；DebugLoop。
- **升级**：SSG/PGL → TPC（语言编译成程序/契约）；SVL/OPT → CTA（支撑地形+四类接触）；NRB → IMR（状态突变+保守触发+回放数据）；“跨五轴” → “组合泛化 + 跨机器人隐藏轴”。
- **纠正**：排名规则、10 次运行结构、每天 1 槽、榜单占位。
- **新增**：ESS、LSG、CFI、HVA。
- **砍/降**：见 2.3。

## 3. 方案轮廓（细节在产物区）

```text
language (160 paraphrases) ──► TPC 任务程序 (steps/weights/pre-post/contact contract)
                                      │
                           ┌──────────▼──────────┐
                           │ ESS 四层状态作用域    │  Port / Episode / Task / Model
                           │  reset→清 Episode     │  audit / no cross-port
                           └──────────┬──────────┘
                                      │ state prompt (short, typed)
                                      ▼
   HVA 执行层：ground → stage → transport → [VLA contact] → release → verify → retry
                                      │
                     ┌────────────────┼────────────────┐
                     ▼                ▼                ▼
                 LSG 指代/序数     CFI 桌面/相机系     CTA 支撑/接触地形
                 target-anchor     每端口标定          PLACE/INSERT/CLOSE/STACK
                     └────────────────┼────────────────┘
                                      ▼
                           GPR-VLA（单 checkpoint）
                           goal z* − belief b → residual → action expert → chunk
                                      │
                                      ▼
                           IMR：干扰/失败监测 → 状态更新 → 重规划/重试（保守）
```

一次 episode 的时序：

1. `reset(port)`：清 EpisodeScope；读 PortScope 标定；如果首次/漂移，估桌面平面/相机系；加载 TaskProgram。
2. 第一帧：LSG 找物体/容器/支撑面；ESS 初始化物体状态；TPC 定位当前步骤。
3. 每个 chunk：state prompt + 当前步骤 instruction + 4 路 RGB + proprio → VLA/HVA；CTA 对接触段做动作整形；执行；验证 postcondition。
4. 干扰：IMR 比对预期/观测；若物体被移动/步骤被撤销，更新 ESS；若当前步骤失效，重规划/重试；否则继续（不轻易停）。
5. 成功/失败/超时：写审计；保留失败回放；不跨 episode 复用。

## 4. 风险与合规（先立后破）

- **单模型边界**：VLA 是唯一学习模型；TPC/ESS/CFI/CTA/IMR 都是确定性代码/几何。推理期不调用外部 LLM/SAM/检测器；LSG 用 VLA 自己的视觉编码器 + 几何聚类。若离线用 LLM 写程序，披露且不依赖。
- **外部数据**：手册未明文禁止，也未明文允许；L2L/合成数据挂在合规开关后，默认只做协议/离线实验；邮件确认。
- **状态隔离**：共享后端 + 每端口 StateStore；互操作测试/模糊测试；审计日志；端口间零共享可变状态。若官方要求更严，退化为每端口独立进程。
- **相机外参**：API 不给 camera_params；用数据集标定 + 离线 CalibAll 式外参 + 在线桌面平面；兜底相机系/相对动作。不要把离线标定当真理。
- **立体深度**：480×640、58mm 基线，远距/透明/反光物体深度差；近距用 wrist 视觉伺服；不承诺毫米级。
- **无力/触觉**：G1 API 没有力矩/力/触觉；插入/闭合靠视觉预插、柔顺搜索、seat 验证；不写“力控”。
- **恢复误报**：RESCUE 的 2–3.3% 误报预算；IMR 默认只更新状态/继续，只有高置信状态证伪才重规划；离线先测误报。
- **每天 1 槽**：真机只做发布门；完整 32 任务计分优先；单任务调试只用于致命问题；best submission 保留，早提交有效成绩可占 tie-break。
- **榜单占位**：不按占位数字调参；只用难度先验做任务采样。
- **Harness VLA 重叠**：它是最近先例；我们明确采用其 harness 哲学，delta 是官方程序/状态隔离/接触地形/标定；实验里把它当基线。
- **基础模型能力**：WLA-1.0-Base 6B 可能对子任务 prompt/状态 prompt 不敏感；先做小样本探针；不敏感就退化为端到端 + 外层验证。
- **算力/延迟**：N 端口共享 6B 后端；批处理/缓存；180s 预算；状态 prompt 短；动作 chunk；RTC 式延迟弹性作为工程件。
- **安全**：不主动行走/底座大范围移动；pivot 限定演示分布；动作限幅/碰撞检查/急停；桌面工作区。

**Kill criteria**：若离线/真机上 ESS/CFI/CTA 的消融增益 <1pp，砍掉对应件；若 Harness VLA 基线追平完整系统，砍掉额外复杂度；若 IMR 误报 >5%，退化为被动日志；若基础模型对状态/子任务 prompt 不敏感，退回端到端 + 外层验证；若真实榜单头部远高于 30%，重新评估边际收益。

## 5. 一句话押注

**押注 STAR-GPR：把官方“端口/历史状态严格隔离”从部署要求提升为第一性架构——语言编译成可验证的接触契约，每端口维护独立的 episodic 状态与桌面/相机标定，用立体支撑地形参数化 PLACE/INSERT/CLOSE/STACK，用官方人类干扰剧本做保守恢复；这是一次改动同时打成功率闸门、人为干扰轴和跨机器人隐藏轴。**

## 1. 事实核对（2026-10-27）

### 1.1 排名规则：成功率主，步骤分次，时间再次

中文手册 4.3.2 原文：

> 最终排名依次依据：总平均成功率 > 总平均步骤分 > 提交时间。

4.3.3 原文：

> 榜单取 32 个任务总平均成功率最高的一次作为该队伍的最终成绩；若总平均成功率得分相同，则取总平均步骤分得分最高的一次；若仍相同，则取该次评测提交时间最早的一次。

含义：

- 32 个任务等权；每个任务 10 次运行等权；总平均成功率 = 所有任务/运行的成功 indicator 平均。
- 步骤分只在成功率打平时决定名次；不要为了部分分牺牲全任务成功。
- 多次提交取最好的一次；早期提交一个有效完整成绩，能在“成功率/步骤分相同”时占提交时间优势。
- “榜首<30%”不是官方数字；截至 2026-10-27 真实榜单未发布。

### 1.2 10 次运行是 5 类 ×2 的组合

手册 2.1 原文要点：

> 每个任务执行 10 次独立运行，每次运行采用不同的泛化设定；10 次运行中包含以下 5 种泛化类型，每种类型各出现 2 次。

5 类：位置、干扰物、桌面背景、未见物品、人为干扰。每次运行是多种设定的组合，不是“每个轴单独测 2 次”。因此：

- 不能做“单轴 +Δ = Δ/5”的线性归因；轴效应混叠。
- 终局接触在 10 次运行都出现，是跨组合的公共因子。
- 失败分析要用 per-run 日志（任务、试次、观测、干预、结果），不能只用任务级平均。

5.1 的机器人分配原文要点：

> 同一任务的不同泛化场景将在同一台真机上评测，但不同任务在每次测评中将随机分布在各台物理机器上进行评测。此外，同一泛化场景在多次测试中亦可能分配至不同物理机器人上执行。

含义：

- 同一任务的 10 次运行：同一台物理机器人 → 该任务的标定/桌面几何在 10 次内近似恒定，可缓存。
- 不同任务：可能换机器人 → 全局标定不够，必须每端口在线标定。
- 跨提交/跨测试：同一场景可能换机器人 → 离线标定不能当真理，必须在线校验。
- “跨机器人”不是第六个泛化轴，是隐藏的标定/几何 nuisance。

### 1.3 每天 1 槽，计分/调试共用，计分必须全 32 任务

手册 3.3 原文：

> 每支队伍每日仅可预约一个测试时段。

3.4 原文要点：

> 计分测试（Multitasks）：单次提测须包含同一机型的全部 32 个任务。
> 不计分测试（Single Task for test）：仅选择单个任务进行调试。

3.3 还规定：参赛方原因导致未能按时接入/测试失败，视为本次机会已使用；赛事方原因才可能补测。含义：

- 没有“调试槽 + 计分槽”两条独立通道；一天一次，二选一。
- 真机是发布门，不是调参器；本地 mock/离线回放承担大部分迭代。
- 完整 32 任务计分跑的数据量最大，且计入 best submission；单任务调试只用于定位致命接口/安全问题。
- 赛前至少留 2 次完整计分跑：一次验证，一次最终；不要把所有希望压在最后一天。

### 1.4 N 端口/状态隔离是硬要求

手册 3.5.3 原文要点：

> 本次评测将在 N 台 G1 机器人上随机分配任务进行测试（N 的具体数量由组委会另行通知），每台机器人承担 32 个任务中的若干项。评测端为每台机器人固定连接一个端口进行交互，因此参赛者须对外暴露 N 个连续端口，从 8765 起（8765, 8766, ..., 8765+N-1）。

多端口共用模型时原文：

> 不同端口可能被同时调用，共享后端须能并发处理，避免相互阻塞、拉高时延；
> 每个端口对应一台独立机器人的独立任务，各端口的 reset 与历史状态须严格隔离，不可串用。

含义：

- N 未公布；按 N=5 或更大做容量规划（示例 N=5，实际未公布；并发/显存/端口都要留余量）。
- 端口 → 机器人 → 任务；端口是隔离键。
- 共享权重可以；共享可变状态不可以。
- 并发请求要能同时处理；不能让一个端口的长任务阻塞另一个端口。
- 官方推荐“每端口独立 server”最稳；共享后端是省显存方案，必须做隔离审计。

## 2. 头部<30% 的失败结构（工作假设）

### 2.1 成功率闸门算术

总平均成功率：

```text
S = (1/32) * sum_t (1/10) * sum_r 1[task t, run r succeeds]
```

每个任务要求所有步骤完成；任一步失败/超时 = 该 run 失败。若任务有 k 步、单步成功率 p、步间独立近似：

```text
P(task success) ≈ p^k
p=0.8: k=2 -> 64%, k=3 -> 51%, k=5 -> 33%
p=0.7: k=2 -> 49%, k=3 -> 34%, k=5 -> 17%
```

如果最后一步接触成功率只有 0.5，前面 0.9：k=3 → 40.5%，k=5 → 32.8%。32 个任务 2–5 步，终局权重 39.8%；整体 <30% 完全可以是“前几步还行、最后一下/最后几步掉”的结果，不需要“感知崩溃”。

### 2.2 占位榜的弱先验

以占位榜首 MolmoAct2 的 task_metrics 为例（**合成数据，只作弱先验**）：

| 类型 | 任务（成功率） |
|---|---|
| 最低成功率 | DisconnectEthernet 21.29、PickOutBattery 23.46、Unlock 23.52、PlacePhotoFrame 24.33、OrganizePencilCase 24.95、FoldTowel 27.19、HangCup 27.29、PackPhone 27.39 |
| 最大步骤分−成功率差 | ColorArrangement 11.69、OrganizeTools 11.65、PackDoll 11.59、PaperCupStacking 11.05、RemovePinnedNote 10.57、ZipUp 10.46、OrganizeBookshelf 10.34、ArrangePlates（占位名 Clear Plates）10.25、ConveyorSorting（占位名 Conveyor Food Sorting）10.10、FruitSorting 9.95 |

解释：

- 最低成功率集中在网线/电池/锁/相框/笔盒/毛巾/挂杯/手机：接触、关节、细长物、透明/反光、堆叠。
- 最大 gap 集中在多步/最后一步：说明“做到大部分、倒在最后”的结构可能存在。
- 但这是合成数据；**不要按这张表调参**，只用它选实验任务（T05/T07/T10/T11/T12/T17/T19/T26/T27/T31）。

### 2.3 组合泛化：为什么单轴补丁不够

10 次运行是 5 类 ×2 的组合；模型要同时处理位置、干扰物、背景、未见物品、人为干扰。一个“每轴 90%”的模型，在组合下可能只有 0.9^5≈59%，再乘上多步接触，落到 30% 以下。含义：

- 单轴补丁的边际收益被组合稀释；跨组合的公共因子（终局接触、状态、标定）更值钱。
- 不能用“这一轴最弱”做预算；要用 per-run 失败标签 + 任务级结果做诊断。
- 语言/未见物体/背景是“输入分布”问题；终局接触/状态/标定是“执行与验证”问题；两类都要，但后者更接近成功率闸门。

### 2.4 最后 3 厘米：终局接触的四种失败

| 类型 | 典型任务 | 失败 | 需要的验证 |
|---|---|---|---|
| PLACE | T01/T03/T08/T20/T21/T25/T27 | 释放过高/姿态不对/没放稳/放偏 | 支撑面/法向/稳定性/沉降 |
| INSERT（含反向拔出） | T05/T10/T26/T32 | 轴不对/深度不够/没到位/拔不出 | 轴/预插/搜索/seat/拔出方向 |
| CLOSE/ARTICULATE | T09/T12/T14/T17/T18/T19/T23/T28/T29/T31 | 拉链/铰链/锁/瓶盖/盖子没闭合/夹到 | 关节轴/方向/终点/视觉状态 |
| STACK | T20/T27/T25 | 中心偏/倾斜/滑落 | 中心/支撑/稳定性 |

占位榜步骤分−成功率 ≈9pp，说明“部分步骤完成但终局失败”的比例不低；这与 39.8% 终局权重、59.7% 放置类权重一致。180s 预算 vs 演示 episode 中位 ~5.9s（HangCup）意味着有充裕时间做 2–3 次 settle/verify/retry；不要把时间花在无效的反复抓取上。

### 2.5 隐藏机器人轴：标定是公共因子

同任务同机、跨任务换机、跨测试换机 → 每台机器人的相机安装、桌面高度/倾斜、光照、背景可能不同。一个在演示机器人上拟合的全局外参/桌面高度，换机就可能偏几厘米；对插入/堆叠/闭合是致命的。对策：

- 每端口在第一次 `reset` 估计桌面平面/相机系；存 PortScope；后续 episode 校验/复用。
- 用 EE 位姿 + wrist 相机做手眼/桌面细化；用 head stereo 做全局支撑图。
- 动作优先用**桌面系/相机系/相对位姿**，少依赖全局 base 外参；必要时回退 joint + IK。
- 离线用 CalibAll 式方法从 33k 演示估外参；在线只做小修正。
- 标定残差大 → 重建；跨端口绝不共享。

### 2.6 人为干扰：状态被改写，不是策略失败

官方备注的干扰是“移动物体/撤销步骤/拿走目标/移动支撑/移动动态目标”，不是“对抗攻击”。无记忆策略的典型错误：

- 人把叠好的第二个碗拿走（T27），策略以为已经完成，继续叠第三个/结束；
- 人把拉链拉开（T19），策略以为已闭合，不再动作；
- 人把插头拔起（T10），策略没检测到，继续按“已插入”执行；
- 人把架子挪走（T08/T21），策略按旧坐标抓空。

所以 IMR 的第一职责是**更新状态**，第二职责才是**重规划**；不是“检测失败→停止”。RESCUE 的结论很重要[S24]：在 stop-and-reset 模型下，理想检测器也只能承受 2.0–3.3% 误报；恢复并不总是提高可恢复性，取决于 state–intervention 对。因此：

- 只有“高置信、持续、使当前步骤 postcondition 失效”的状态变化才触发重规划；
- 否则继续执行/观察；
- 不用“异常检测”代替状态验证；
- 先离线统计误报，再上真机。

### 2.7 头部路线对比

| 路线 | 代表/证据 | 强项 | 在 UniBot 的软肋 | 对我们的含义 |

### 2.8 假设的可证伪点

| 假设 | 证伪方式 | 如果被证伪 |
|---|---|---|
| 状态（ESS）是主要增益 | 无状态 vs 有状态消融；人为干扰子集 | 砍 ESS 到轻量日志，转向 LSG/CTA |

## 3. STAR-GPR 架构

### 3.1 总览

```text
                         ┌─────────────────────────────┐
language ──► TPC ───────►│ TaskProgram (32 tasks ×5)   │
                         │ steps/weights/pre-post      │
                         │ contact contract/success    │
                         └──────────────┬──────────────┘
                                        │ current step + contract
                         ┌──────────────▼──────────────┐
                         │ ESS: Port / Episode / Task   │
                         │ /Model scopes; audit; reset  │
                         └──────────────┬──────────────┘
                                        │ state prompt (typed, short)
   4×RGB + proprio ──► LSG ──► objects/relations/ambiguity
                         │              │
                         │       CFI: table/camera frame, per-port calib
                         │              │
                         ▼              ▼
                  HVA: GROUND → STAGE → TRANSPORT → VLA_ACT → RELEASE → VERIFY → RETRY
                                        │
                         ┌──────────────┼──────────────┐
                         ▼              ▼              ▼
                       CTA          GPR-VLA          IMR
                  support/contact  goal/residual   monitor/replan
                  PLACE/INSERT/    action expert   official scripts
                  CLOSE/STACK      chunk           conservative
                         └──────────────┼──────────────┘
                                        ▼
                                   action chunk
```

单模型原则：只有 GPR-VLA 是学习模型；TPC/ESS/LSG/CFI/CTA/IMR 是确定性代码/几何/规则；ICR 的库是数据；L2L 的数据只在训练期（且合规开关）。推理期不调用外部 LLM/SAM/检测器。LMP 证明“语言→程序/原语”的路线可行，但我们把 LLM 放在离线编译，推理期不调用[S28]。

### 3.2 HVA：Harness 执行层

采用 Harness VLA 的核心思想[S11]：**冻结/微调的 VLA 只做 contact-rich 段；外层用固定原语做 grounding、staging、transport、release、retry。** 但把 Harness VLA 的“记忆增强 agent/可能的外部 LLM”替换成**确定性任务程序 + 状态机**，以满足单模型/低延迟/可审计的要求。

原语（全部确定性，不含学习参数）：

| 原语 | 输入 | 输出 | 用途 |
|---|---|---|---|
| GROUND | 程序角色 + 观测 | 物体/容器/支撑位姿 + 置信度 | 找目标、槽位、支撑面 |
| STAGE | 当前位姿 + 预接触位姿 | 关节/EE 轨迹 | 预抓/预插/预放 |
| TRANSPORT | 抓取位姿 + 目标位姿 | 轨迹 | 搬运，避障 |
| VLA_ACT | 当前观测 + 子任务 prompt + 状态 prompt | action chunk | 接触密集段（抓/插/闭合/放置微调） |
| RELEASE | 支撑面 + 释放参数 | 夹爪/末端动作 | 放置/堆叠释放 |
| VERIFY | 期望 postcondition + 观测 | 通过/失败/不确定 | 步骤验证 |
| RETRY | 失败类型 + 状态 | 重试/重抓/重规划 | 恢复 |

接口：

```python
def execute(primitive: str, args: dict, state: EpisodeState) -> ActionChunk:
    ...
```

HVA 的增益边界：

- 如果端到端 VLA 在接触段已经很强，HVA 的收益主要来自状态/验证/重试，不是“换控制器”；
- 如果 VLA 在非接触段（搬运/接近）也容易漂，HVA 的确定性原语能省掉很多失败；
- 如果任务程序写错，HVA 会稳定地执行错；TPC 的离线验证同样重要。

### 3.3 TPC：任务程序编译器

输入：

- 官方 `score_steps`（步骤/权重）；
- 官方任务描述/视频；
- 每条任务 5 条英文复述（160 条）；
- 表 B 的人类干扰备注；
- 物体角色/属性/空间关系（人工标注 + 数据统计）。

输出 `TaskProgram`：

```json
{
  "task_id": "T26",
  "paraphrases": ["...", "...", "...", "...", "..."],
  "objects": {
    "cable": {"role": "target", "attrs": ["black", "thin"]},
    "port": {"role": "receptacle", "attrs": ["network", "slot"]}
  },
  "steps": [
    {"id": 1, "instruction": "Grab the ethernet cable", "weight": 30,
     "pre": ["gripper_open", "cable_visible"],
     "post": ["cable_grasped"],
     "contract": {"type": "grasp", "approach": "top", "clearance": 0.02}},
    {"id": 2, "instruction": "Hold the network port", "weight": 30,
     "pre": ["port_visible"], "post": ["port_held"],
     "contract": {"type": "hold", "axis": "port_normal"}},
    {"id": 3, "instruction": "Plug the cable into the network port", "weight": 40,
     "pre": ["cable_grasped", "port_held"],
     "post": ["cable_seated"],
     "contract": {"type": "insert", "axis": "port_normal",
                  "depth": 0.012, "search": "spiral", "verify": ["visual_seat"]}}
  ],
  "success": ["cable_seated"],
  "human_scripts": [
    {"trigger": "after_step_2", "mutation": "move(cable, left, 0.05)"},
    {"trigger": "after_step_2", "mutation": "move(port, left, 0.05)"}
  ]
}
```

在线匹配：

1. 用 VLA 文本编码器编码 instruction；
2. 与 160 条复述的嵌入做余弦匹配；
3. 中文指令用 32 个任务关键词/模板映射到程序 ID（确定性，不用翻译模型）；
4. 匹配失败 → 用原始 instruction + 通用程序（只做 GROUND/VLA_ACT/VERIFY），并记录 OOD。

状态 prompt：把当前步骤、pre/post 状态、物体角色、支撑面、干扰日志渲染成短文本（<256 tokens），与当前步骤 instruction 一起喂给 VLA。例：

```text
TASK T26 PlugInEthernet | STEP 3/3: plug cable into port
DONE: cable grasped; port held
OBJECTS: cable@(0.42,0.11,0.03) grasped; port@(0.55,0.20,0.08) held
SUPPORT: table z=0.00; port axis=(0,0,1); clearance=0.02
INTERVENTION: none
NEXT: align tip; insert 0.012 m; verify seat
```

TPC 的关键不是“写 32 个 JSON”，而是**把评分步骤变成可验证谓词**。没有谓词的步骤，HVA 无法判断是否完成；没有接触契约的步骤，CTA 无法参数化。

### 3.4 ESS：Episodic State Store

四层作用域见 0.2/1.1。核心 schema：

```json
{
  "port": 8765,
  "episode_id": "uuid",
  "task_id": "T26",
  "step": 3,
  "objects": {
    "cable": {"pose": [0.42,0.11,0.03,0,0,0], "state": "grasped", "conf": 0.91},
    "port":  {"pose": [0.55,0.20,0.08,0,0,0], "state": "held", "conf": 0.88}
  },
  "support": {"plane": [0,0,1,-0.00], "regions": ["table", "rack"], "normals": "..."},
  "calibration": {"table_frame": "...", "head_T": "...", "wrist_T": "...", "residual": 0.004},
  "interventions": [{"t": 12.3, "object": "cable", "delta": [0.05,0,0], "source": "human_script"}],
  "history": [{"step": 1, "result": "ok"}, {"step": 2, "result": "ok"}],
  "audit": ["..." ]
}
```

Chameleon 把记忆拆成可分/可寻址/可前瞻三点[S13]；ESS 的 schema/审计就是这三点的工程化。不变量（必须写成代码断言 + 测试）：

1. 所有可变状态在 StateStore；模块不得有全局可变变量。
2. `get(port, episode)` 只返回该端口该 episode 的状态；跨端口读抛异常。
3. `reset(port)`：
   - 清 `EpisodeScope`（objects/step/history/interventions）；
   - 保留 `PortScope`（calibration/robot_id）；
   - 不触碰其他端口。
4. `TaskScope`/`ModelScope` 只读；推理期不更新权重。
5. 每次写状态：`(port, episode, t, field, old, new, source)` 审计；可回放。
6. 并发：每个端口一个请求队列/锁；共享后端只共享只读权重；KV/缓存按 port 分区。
7. 大标定漂移（残差 > 阈值）→ 重建 PortScope 标定；记录事件。

状态隔离测试（本地 mock）：

```python
# 交错两个端口，两个任务
for step in range(100):
    obs_a, obs_b = interleave(port_a, port_b)
    act_a = policy.get_action(obs_a)   # port 8765
    act_b = policy.get_action(obs_b)   # port 8766
    assert state[8765].episode_id != state[8766].episode_id
    assert state[8765].task_id != state[8766].task_id
policy.reset(port=8765)
assert state[8765].objects == {}
assert state[8766].objects != {}      # 不受影响
```

模糊测试：随机 reset/请求/端口交错 1,000 次；检查无跨端口对象/历史/标定泄漏；检查日志可回放。

### 3.5 LSG：Language-Scene Grounder

输入：4 路 RGB、head stereo 深度（离线标定/在线匹配）、EE 位姿、程序角色。

输出：物体/容器/支撑面的位姿、属性、关系、置信度、歧义标记。

方法（不引入第二个学习模型）：

1. **候选生成**：颜色/深度/边缘/连通域/几何聚类（桌面上的物体、架子的槽位、盒子的内部）。
2. **属性匹配**：颜色/形状/尺寸/材质（从 RGB + 深度）；用 VLA 视觉编码器的特征做相似度（只读，不新增模型）。
3. **关系/序数**：左/右/上/下/前/后、第几个、在…上/里、颜色匹配；用桌面规范系计算。
4. **歧义处理**：target-anchor-frame（RefGuard 式）：同时维护 target/anchor/frame 的后验；能执行就执行，不能就 reobserve（移动 wrist/arm 换视角），仍不确定则选最高后验并验证；不静默早承诺。
5. **未见物体**：用属性/关系而不是类别；如果候选缺失，搜索/重观察；不假设类别检测器。
6. **主动感知**：ActiveVLA 的思路可借[S40]，但 API 不能直接控制相机；用腕/臂换视角，不额外加相机。

证据：RefGuard 在 90% 歧义压力测试正确执行、无 identity switch[S14]；Spa-Bench 显示空间 grounding 的 OOD 下降很大，直接操作指令可 +28–40pp[S33]；AnySlot/SpaceVLA/ActGaze 支持显式目标/锚点/动作注意力[S34][S35][S36]。

单模型合规：LSG 的“学习”部分只用 VLA 自己的视觉/文本编码器；分割/聚类是确定性几何。若离线用 SAM 做标注，标注数据可以训练 VLA，但推理期不加载 SAM。

### 3.6 CFI：Canonical Frame Isolation

目标：把“换机器人/换桌子/换相机”变成可处理的几何，而不是策略的隐变量。

四个坐标系：

- **Base**：机器人 base（API 的 EE 位姿就是 base 系）。
- **Table**：桌面规范系（原点在桌面一角/中心，z 垂直桌面）；由 head stereo 平面 + 法向估计。
- **Camera**：左/右 head、左/右 wrist；由离线标定 + 在线验证。
- **Object/Support**：物体/支撑面局部系；由 LSG/CTA 估计。

流水线：

1. **离线**：用 33k 演示 + `camera_params` + EE 位姿，估 head/wrist 到 EE/base 的外参（CalibAll 式[S21]；PnP/手眼）；统计桌面高度/法向分布；训练时做相机/桌面随机化。
2. **在线 reset**：用 head stereo 深度 + RANSAC 估桌面平面；用 EE 位姿 + wrist 相机细化；存 PortScope；与上一 episode 的残差比较；大漂移重建。
3. **动作**：优先在 Table/Camera 系生成目标，再变换到 Base；如果外参不可信，回退 Camera/相对动作（OC-VLA++/IronMind[S22][S39]）；joint 模式下用 IK 把 Table 系目标变关节。
4. **验证**：每 N 步用支撑图/EE 位姿检查标定残差；残差大 → 重估/降速/保守动作。

注意：

- API 不给 head 相机外参；`camera_params` 是数据集的 nominal，不是真机保证。必须在线验证。Self-Adaptive VLA 用自身 rollout 作为上下文，在硬件偏移下恢复 >80%[S12]；我们优先用在线标定/相机系动作，若数据足够再加端口上下文 token。
- 左右 cx 有差异，`rectified: true` 也不能假设完美极线；用 R/T 或在线极线校正。
- 透明/反光/远距物体深度差；近距用 wrist 视觉伺服，不承诺毫米级。
- 同任务 10 次同机 → PortScope 标定可复用；跨任务换机 → 每端口重建；跨提交换机 → 在线校验。

### 3.7 CTA：Contact Terrain Adapter

支撑图：

- head stereo → 点云/深度 → 桌面平面 → 高度图（相对桌面）→ 法向 → 支撑区域/障碍/槽位/边缘；
- wrist RGB → 近距边缘/纹理/孔位/拉链齿；
- 支撑图不是“重建整个场景”，只保留任务相关区域（桌面、架子、盒子、传送带、布料）。

四类接触模板：

#### PLACE

```json
{"type":"place","target":"support_region","normal":"n",
 "release":{"height":0.003,"tilt_tol_deg":3,"settle_s":0.5},
 "verify":["contact","stable","centered"],"retry":{"max":2}}
```

参数：释放高度、姿态对齐支撑法向、稳定性判据（Placeability 式[S16]）、沉降时间、重试。适用 T01/T03/T08/T20/T21/T25/T27 等。

#### INSERT

```json
{"type":"insert","target":"hole","axis":"hole_axis",
 "pre":{"offset":0.03,"tol":0.005},
 "search":{"pattern":"spiral","radius":0.004,"speed":0.01},
 "depth":0.012,"verify":["visual_seat","slack"],"retry":{"max":2}}
```

参数：孔轴、预插偏移、螺旋/锯齿搜索、深度、seat 视觉验证、拔出方向（T05 用反向）。适用 T05/T10/T26/T32。无力传感器：用视觉预插 + 柔顺搜索 + 轻触/微动；不写“力控”。TacVLA/Opt2VLA 说明触觉/力感知的收益，但本 API 无这些观测，故不采用[S29][S30]。

#### CLOSE

```json
{"type":"close","target":"zipper","axis":"edge",
 "grasp":"tab","direction":"along_edge","end":"closed",
 "verify":["closed_visual"],"retry":{"max":2}}
```

参数：铰链/拉链/锁/瓶盖/盖子的轴、抓点、方向、终点、视觉验证。适用 T09/T12/T14/T17/T18/T19/T23/T28/T29/T31。

#### STACK

```json
{"type":"stack","object":"bowl_3","support":"bowl_2_rim",
 "center_tol":0.005,"release":{"height":0.003,"settle_s":0.5},
 "verify":["stable","centered"],"retry":{"max":1}}
```

参数：中心对齐、支撑面、释放高度、稳定性、重试。适用 T20/T27/T25。

动作整形：

- VLA 输出 action chunk；CTA 在接触段做平移/旋转/缩放/释放高度修正；
- 接近段：沿支撑法向/孔轴预对齐；
- 插入段：小步、低速、搜索；
- 释放段：缓放、settle、视觉验证；
- 失败：按失败类型重试/重抓/重规划，不盲目重复。

证据：Placeability[S16]、VFAL[S17]、StereoPatch[S23]、AOMGen/SMART[S19][S20]。

### 3.8 IMR：Interference Monitor & Replanner

监测信号：

- 物体位姿/可见性 vs 期望；
- 当前步骤 postcondition 是否仍成立；
- 支撑面/架子是否移动；
- 夹爪开度/EE 位姿 vs 动作；
- 视觉变化区域（人/手/物体）；
- 时间/进度（是否卡住）。

触发规则（保守）：

1. **高置信 + 持续 + 使当前步骤失效** → 重规划；
2. 只改变外观/不改变任务状态 → 继续；
3. 不确定 → 再观察（wrist/arm 换视角），不立即停；
4. 目标被拿走/找不到 → 搜索/等待/安全失败；
5. 误报预算 <3%；超过则降级为被动日志。

响应：

- 更新 ESS（物体位姿/状态/步骤）；
- 若步骤被撤销 → 回滚到该步骤之前，重做；
- 若物体被移动 → 重新 GROUND/STAGE，继续；
- 若支撑被移动 → 重建桌面/支撑图，重规划；
- 若动态目标（传送带）→ 重跟踪/重规划；
- 记录 intervention/recovery 日志，供离线学习。

官方剧本映射（示例）：

| 任务 | 剧本 | IMR 响应 |
|---|---|---|
| T27 | 叠第二个后拿走第二个 | 检测 bowl_2 消失/被移走 → 回滚“叠第二个”，重新叠 |
| T19 | 拉上拉链后拉开 | 检测 closed→open → 重做 close |
| T14 | 拧开盖子后拧回 | 检测 cap open→closed → 重做 open |
| T17 | 笔盒合上后手动打开 | 检测 closed→open → 重做 close |
| T16 | 叠好的毛巾翻开 | 检测 folded→unfolded → 重做 fold |
| T10 | 插头拔起 | 检测 seated→unseated → 重做 insert |
| T08 | 抓书后挪架子 | 检测支撑移动 → 重建支撑图，重规划 |
| T21 | 把架子向左 | 同上 |
| T25 | 放第一个后挪底座 | 检测支撑/底座移动 → 重建，继续 |
| T24 | 可乐/薯片快到了放回起点 | 检测目标位置跳变 → 重跟踪/重规划 |

注意：备注编号/触发时机未官方解释；上表是“剧本素材”，不是精确评测条件。IMR 要能处理同类突变，而不是只认这几条。

数据：

- 用官方演示 + 剧本在离线回放/仿真中生成“状态突变→恢复”数据（Kintsugi 式[S26]）；
- 用 SocialVLA 的“人类反应作为干预信号”做辅助[S27]；
- 用 Hide-and-Seek 的轨迹失败信号做监测特征[S25]；
- 真机只验证子集；不在真机上大规模试错。

### 3.9 GPR-VLA：状态提示 + 子任务提示 + 接触残差

保留第 7 轮的主干：目标 z*、部件信念 b、残差 r、action expert、可逆信念。增量：

1. **状态提示**：把 ESS 的当前步骤/对象/支撑/干扰渲染成短文本，与 `observation.language` 一起进 VLA 文本编码器；训练时随机 dropout/扰动状态，避免模型忽略。
2. **子任务提示**：当前步骤 instruction 作为 prompt；可选加一个小的子任务分类头（32 任务 ×2–5 步），但优先用 prompt（零新增参数、单模型）。
3. **接触残差**：CTA 的接触契约参数（释放高度/插入深度/轴/搜索半径）编码成低维向量，注入 goal/residual 或 action expert 的 conditioning；如果不稳，先用手工动作整形，不改网络。
4. **视觉条件**：4 路 RGB + 深度/支撑图（可选）；如果模型不吃深度，用 RGB + 几何后处理，不强行改输入。
5. **损失**：沿用动作生成损失；可选加 postcondition/子任务辅助损失；状态 prompt dropout；相机/桌面随机化增强。
6. **单 checkpoint**：不做每任务 LoRA；最多一个全局 LoRA；推理期权重冻结。

如果 WLA-1.0-Base 对文本状态/子任务 prompt 不敏感（小样本探针），退化方案：

- VLA 只做端到端动作；
- HVA/CTA/IMR 在动作外层做整形/验证/重试；
- 状态不放 prompt，放规则/动作参数；
- 这样仍然是单模型 + 确定性外层，只是少了“状态条件化”的增益。

### 3.10 一次 episode 的伪代码

```python
def reset(port):
    store.clear_episode(port)                  # 只清 EpisodeScope
    calib = store.get_port(port).calibration  # 复用/校验
    obs0 = None
    return

def act(obs, port):
    ep = store.episode(port)
    if ep is None:
        ep = store.start_episode(port, obs)
        ep.program = TPC.match(obs.language)
        ep.step = 0
        ep.support = CFI.estimate_support(obs)       # 桌面/相机系
        ep.objects = LSG.ground(obs, ep.program)      # 目标/容器/支撑
    ep.step = TPC.current_step(ep, ep.objects)        # 根据 postcondition
    prompt = TPC.render_state_prompt(ep)
    contract = ep.program.steps[ep.step].contract
    primitive = HVA.choose(ep, contract)              # GROUND/STAGE/TRANSPORT/VLA_ACT/...
    if primitive == "VLA_ACT":
        action = GPR_VLA.act(obs, prompt, contract)
        action = CTA.shape(action, ep, contract)
    else:
        action = HVA.execute(primitive, ep, contract)
    ok, why = CTA.verify(obs, ep, contract)           # PLACE/INSERT/CLOSE/STACK
    if ok:
        ESS.mark_done(ep, ep.step)
    else:
        ev = IMR.check(obs, ep, why)                  # 状态突变/失败
        if ev.invalidates_current_step:
            ESS.update_from_intervention(ep, ev)
            HVA.replan(ep, ev)
        elif ev.confidence > 0.8:
            ESS.log(ep, ev)                           # 继续观察
    ESS.audit(port, ep)
    return action
```

关键点：`act()` 不持有跨端口/跨 episode 的可变全局状态；所有状态在 `store`；`reset` 只清 episode；`VLA_ACT` 是唯一学习模型调用；验证/重试在外层。

## 4. 数据引擎（TLE/ACP/GF 修剪版）

### 4.3 人类干扰回放

对每条演示：

1. 按表 B 的模式选一个触发时刻（步骤完成后/抓取前/搬运中）；
2. 对目标/容器/支撑施加 1-DOF 平移/旋转/拿走/撤销；
3. 记录干预前后的状态、物体位姿、成功谓词；
4. 用当前策略/脚本生成恢复动作；
5. 标注“恢复成功/失败/无需恢复”。

这不是“仿真环境的精确复刻”，而是**状态突变→恢复**的数据。IMR 学的是“状态被改写后怎么办”，不是“识别某条备注”。

### 4.4 跨机器人/标定增强

- 随机化 head/wrist 外参（小角度/小平移）、桌面高度/倾斜、光照、背景、相机噪声；
- 训练 camera-frame/relative action，减少对 base 外参的依赖；
- 在离线回放中模拟“同任务同机、跨任务换机、跨测试换机”；
- 评估 CFI 的标定残差与成功率关系；
- 不要把随机化开到“现实不可能”的程度；以官方数据统计为边界。

## 5. 训练配方

### 5.1 底座与单模型

- 首选 **Unitree UnifoLM-WLA-1.0-Base（6B，Apache-2.0）**；官方称 24GB 可微调（以模型卡为准）[S31]。

- 动作空间：默认 EE（便于桌面系/位姿契约/迁移）；若底座只支持 joint，则 joint + IK/动作整形。
- 图像：4 路；训练 480×640 或 240×320（按显存/延迟）；推理可 resize；head stereo 保留较高分辨率用于几何。

| 阶段 | 数据 | 目标 |

### 5.3 损失/条件化

- 主损失：底座原有的动作生成损失（flow/diffusion/regression，以模型卡为准）。
- 可选辅助：子任务分类/进度预测（FineART 式[S15]）；postcondition 预测；状态 prompt 对比/重构（轻量）。
- 状态 prompt：训练时随机 dropout 20–30%，并随机扰动对象位姿/步骤，避免模型“只会读完美状态”。
- 接触参数：先用手工动作整形（不改网络）；若稳定，再把 release height/insert depth/axis 编码进 conditioning。
- 相机/桌面增强：随机外参/高度/光照/背景；camera-frame action 监督。
- 不做：每任务 LoRA、任务特定 head  ensemble、外部 LLM 在线规划、RL 在线试错（真机预算不允许）。

### 5.4 算力/延迟

- 训练：6B 全量/LoRA 需多卡（以官方 24GB 微调为下限；33k 全量建议 8×A100/H100 级别，按实际资源调整）。
- 推理：1×80GB 可跑 6B + N 端口批处理；若 N=5、chunk=8–16、4 路 240×320，目标单 chunk <1s；180s 预算足够 2–3 次重试。
- 优化：半精度/量化（若精度可接受）、KV/视觉缓存、跨端口 batch、动作 chunk、异步执行（RTC 式）作为工程件；Streaming-WAM 的异步 world-action 结构可参考[S41]。
- 监控：P50/P95 延迟、队列、GPU 显存、超时率；延迟高时降分辨率/减相机/减 chunk，不牺牲状态隔离。

## 6. 部署与状态隔离

### 6.1 N 端口拓扑

| 方案 | 做法 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|
| A 每端口独立进程 | N 个 server，各加载一份模型 | 进程级隔离，最稳 | 显存 ×N | 最终计分跑优先，若显存够 |
| B 共享后端 | N 个轻端点 + 共享推理后端 + 每端口 StateStore/队列 | 省显存，易批处理 | 隔离要自己保证 | 6B/N=5 或更大的默认；必须审计 |

端口：8765, 8766, …, 8765+N−1；WebSocket；metadata/token；`obs_delta_indices`/`image_resize`/`action_chunk_size`；`reset()` 每 episode。

### 6.2 StateStore 实现

- 进程内 `dict[(port, episode_id)]`；port 级锁/队列；无模块级可变全局。
- `PortScope`：`robot_id`、`calibration`、`table_frame`、`episode_count`；端口间不共享。
- `EpisodeScope`：`task_id`、`step`、`objects`、`support`、`interventions`、`history`；`reset` 清空。
- `TaskScope`/`ModelScope`：只读；引用共享。
- 审计：JSONL/内存 ring buffer；字段 `(port, episode, t, field, old, new, source)`；可回放。
- 并发：每端口一个请求队列；共享后端按 batch 前向；不跨端口共享 KV/隐状态；请求超时/取消。
- 重启：端口进程重启后从空状态开始；共享后端重启后所有端口清空；不持久化 episode 状态（避免串用）。
- 标定缓存：只在 PortScope；大漂移重建；跨端口不共享。

### 6.3 隔离审计

必须做：

1. 交错请求：两个端口不同任务，100–1,000 步交错；检查 objects/history/calibration 不串。
2. reset 隔离：reset A 不影响 B；reset 后 A 的 episode 状态为空；PortScope 保留。
3. 并发压力：N 端口同时请求；检查队列/延迟/无死锁；检查模型 batch 不混状态。
4. 模糊测试：随机 reset/请求/异常/超时；检查无泄漏/无崩溃。
5. 日志回放：任取一个 episode，能从审计日志重建状态序列。
6. 权重只读：推理期 hash 权重不变；无临时微调。
7. 端口映射：端口 → 机器人 → 任务；日志记录；不跨端口复用 token/请求。

### 6.4 180s/安全

- 时间预算：感知/规划 <1s/chunk；动作执行按演示速度；重试 2–3 次；超时前优雅失败。
- 安全：EE 工作空间限幅；支撑图碰撞检查；不主动行走/底座大范围移动；pivot 限演示分布；急停/人工干预优先。
- 人：检测到人手/人进入工作区 → 减速/暂停/让行；不与人抢物体。
- 失败：不反复撞/卡；超过重试次数 → 放弃当前步骤/任务，保留状态日志。
- 监控：端口健康、队列、GPU、错误率、超时率、状态隔离告警。

### 6.5 提交策略

- 先提交一次**完整 32 任务**的有效计分跑（即使分数一般），占住 best submission/tie-break；
- 之后每次真机优先完整计分跑；单任务调试只用于致命问题；
- 每天 1 槽：赛前至少 2 次完整跑（验证 + 最终）；不要把最终跑放在最后一天；
- 记录每次跑的模型 hash、配置、端口/N、开始/结束、异常；便于复现。

### 7.4 诊断矩阵

- 任务 × 泛化组合 × 机器人 × 步骤 × 失败类型；
- 失败类型：grounding（找错/没找到）、grasp（抓空/滑）、transport（碰撞/掉落）、contact（没到位/过深/没闭合）、release（过高/没稳）、interference（没更新状态）、calibration（偏）、timeout、state leak；
- 每个失败看视频/状态日志，不只看得分；
- 用占位榜只选任务，不用它调参。

## 8. 创新点清单（持续迭代）

> 状态标记：**押注** = 本轮主攻；**保留** = 已有基础；**新增** = 本轮新件；**降级** = 保留但不进主路径；**砍** = 不做。每条给“动机/差异/可行性/资源/步骤/风险”。

### I1 ESS 状态隔离的 episodic state store（新增，押注）

- **动机**：官方明确要求端口/reset/历史隔离；人为干扰会改写状态；无记忆 VLA 会重复/漏做/按旧计划执行。
- **差异**：不是“加 memory”，而是四层作用域（Port/Episode/Task/Model）+ 生命周期 + 不变量 + 审计；把状态隔离从部署要求变成架构。
- **可行性**：纯 Python/进程内状态；无新模型；本地 mock 可测；对现有 VLA 无侵入（状态放 prompt）。
- **资源**：1 人 1–2 周；CPU 内存；无 GPU。
- **步骤**：schema → StateStore → reset/并发隔离测试 → 状态 prompt → 真机日志。
- **风险**：prompt 过长/模型忽略；跨端口泄漏；PortScope 与 EpisodeScope 边界争议。→ 短 prompt、dropout、审计、文档化。

### I2 TPC 任务程序/接触契约编译器（升级，押注）

- **动机**：32 任务 ×5 复述；评分步骤公开；语言需要指代/步骤/验证，不只是 prompt。
- **差异**：把 `score_steps`/复述/人类备注编译成带 pre/post/contact/success 的程序；确定性匹配，推理期不用外部 LLM。
- **可行性**：32 个 JSON 可手工+脚本生成；VLA 文本编码器可匹配；离线可验证。
- **资源**：1 人 2 周；标注/校对。
- **步骤**：schema → 32 程序 → 160 复述匹配 → 谓词/契约 → 留一验证。
- **风险**：程序写错/评测指令超出 5 复述；谓词不可观测。→ 通用 fallback、人工复核、真机日志。

### I3 CTA 立体支撑/接触地形适配（升级，押注）

- **动机**：终局步骤 39.8%、放置类 59.7%；桌面支撑/插孔/关节是失败集中区；API 无力/触觉。
- **差异**：head stereo 支撑图 + 四类接触模板（PLACE/INSERT/CLOSE/STACK）+ 视觉/本体验证；不是“再训练一个接触模型”。
- **可行性**：数据集有 stereo 标定；RANSAC/点云/视觉伺服成熟；动作整形不改网络。
- **资源**：1–2 人 2–3 周；GPU 用于回放。
- **步骤**：支撑图 → 四类模板 → 离线回放 → 真机子集。
- **风险**：深度噪声/透明反光；无力控；模板不适配软物体。→ wrist 近距、柔顺搜索、按任务回退。

### I4 CFI 规范桌面/相机系与每端口标定（新增，押注）

- **动机**：同任务同机、跨任务换机、跨测试换机；API 不给 camera_params；全局标定换机就偏。
- **差异**：PortScope 标定缓存 + 在线桌面平面 + 离线 CalibAll 式外参 + 相机系/相对动作；把隐藏轴变成几何。
- **可行性**：数据集有 camera_params/EE 位姿；CalibAll/OC-VLA++ 有先例；在线 RANSAC 成熟。
- **资源**：1 人 2 周；标定靶/真机一次。
- **步骤**：离线外参 → 在线平面 → 动作系 → 换机测试。
- **风险**：head 外参不可得/极线不完美；深度差；标定漂移。→ wrist/EE 兜底、残差监控、降速。

### I5 IMR 官方干扰剧本的保守恢复（升级，押注）

- **动机**：5 类泛化含人为干扰；表 B 给出逐任务剧本；无记忆策略被撤销后回不来。
- **差异**：状态突变检测（不是失败检测）+ 官方剧本回放数据 + 保守触发（RESCUE 误报预算）+ 状态回滚/重规划。
- **可行性**：剧本可离线回放；无需真机；Kintsugi/SocialVLA 有先例。
- **资源**：1 人 2 周；离线算力。
- **步骤**：剧本解析 → 回放数据 → 监测器 → 触发阈值 → 真机子集。
- **风险**：误报反噬；剧本与真实干扰不符；监测器延迟。→ 高置信/持续/失效三条件、被动日志 fallback、在线校准。

### I6 LSG 语言-场景接地（新增，中优先）

- **动机**：5 复述/未见物体/属性/序数/空间/歧义；指代错会执行“几何正确但语义错”的动作。
- **差异**：target-anchor-frame 后验 + 属性/关系 + VLA 视觉编码器 + 几何聚类；不引入外部检测器。
- **可行性**：RefGuard/Spa-Bench/AnySlot 有先例；几何聚类成熟。
- **资源**：1 人 2 周；GPU 回放。
- **步骤**：候选 → 属性/关系 → 歧义 → 重观察 → 验证。
- **风险**：未见物体/遮挡/透明；VLA 特征不够判别。→ 多视角、语言属性、保守失败。

### I7 HVA Harness 执行层（采用，非新）

- **动机**：Harness VLA 证明冻结 VLA + 固定原语 + 记忆可在扰动下大幅提升；纯端到端不稳。
- **差异**：我们用确定性任务程序替代“记忆增强 agent/外部 LLM”；原语固定；状态隔离。
- **可行性**：原语是代码；VLA 可冻结/微调；接口清晰。
- **资源**：1 人 2 周；无额外模型。
- **步骤**：原语库 → 任务程序驱动 → 重试/验证 → 基线对比。
- **风险**：程序错则稳定错；原语不适配软物体；VLA 接触段不够强。→ 离线验证、按任务回退端到端。

### I8 GPR-VLA 主干（保留）

- **动机**：第 7 轮已有 goal/residual/action expert/可逆信念；WLA-1.0-Base 是人形 VLA。
- **差异**：本轮加状态 prompt/子任务 prompt/接触参数条件化；不改主干。
- **可行性**：已有代码/权重；微调。
- **资源**：GPU 训练。
- **步骤**：P0 复现 → P1 语言 → P2 接触 → P5 整合。
- **风险**：6B 对 prompt 不敏感；微调成本；灾难遗忘。→ 小样本探针、LoRA、官方数据回放。

### I9 ICR 少样本检索（保留，可选）

- **动机**：33k 官方演示可做上下文；检索可补长尾。
- **差异**：关系中心键 + 相位对齐；但不再是主押注。
- **可行性**：ICI-VLA/RA-VLA 有先例[S37][S38]；缓存编码。
- **资源**：1 人 1–2 周；索引/GPU。
- **步骤**：键设计 → 检索 → 上下文条件 → 消融。
- **风险**：透明/布料检索失效；延迟。→ 分桶回退、缓存。

### I10 数据引擎（保留，修剪）

- **动机**：官方 33k 是主数据；合成/回放补接触/干扰/标定。
- **差异**：只做任务相关合成；不做全场景孪生；不做自由仿真。
- **可行性**：AOMGen/SMART/Unitree sim 可用；许可需核。
- **资源**：GPU/存储。
- **步骤**：官方 → 合成 → 回放 → 增强。
- **风险**：sim-to-real；许可；过拟合。→ 域随机化、合规开关、官方为主。

### I11 L2L 实验室数据协议（保留，默认关）

- **动机**：背景/位置/机器人多样性是官方数据短板；高校 G1 实验室可补。
- **差异**：统一协议 + QA + 法务 + 赛后开源；不是“买黑箱数据”。
- **可行性**：已有 G1 采集流水线；需协调。
- **资源**：1 人协调；采集成本。
- **步骤**：协议 → 试点 → QA → 合规确认 → 并入。
- **风险**：数据质量/许可/时间。→ 默认关、试点、书面确认。

### I12 DebugLoop 真机发布门（保留，工程）

- **动机**：每天 1 槽；真机稀缺；需要发布门。
- **差异**：本地 mock/离线为主；真机只验证里程碑；完整计分优先。
- **可行性**：流程/脚本。
- **资源**：1 人 0.5 周。
- **步骤**：mock → 离线 → 真机 → 复盘。
- **风险**：把真机当调参器；单任务调试浪费槽。→ 规则化。

### I13 TCLB 本地孪生（降级）

- **动机**：离线相对比较。
- **差异**：不做高保真全任务孪生；只做任务子集/接触回放。
- **可行性**：Unitree sim。
- **资源**：GPU。
- **步骤**：子集 → 回放 → 相对比较。
- **风险**：sim-to-real；时间。→ 降级，不阻塞主路径。

### I14 FLEET 多端口工程（降级）

- **动机**：N 端口/并发/状态隔离/延迟。
- **差异**：工程检查单，不是研究轴。
- **可行性**：官方模板 + StateStore。
- **资源**：1 人 1 周。
- **步骤**：端口 → 队列 → 隔离测试 → 压测。
- **风险**：并发 bug/泄漏。→ 审计/压测/每端口进程兜底。

### 已砍清单

- 每任务 LoRA/专家集成（规则不允许/成本高）；
- WMA-0/世界模型进主路径（慢/数据饥渴/难验证）；
- 全 32 任务高保真孪生（成本/收益低）；
- 自由仿真数据（sim-to-real/许可）；
- 运行时仿真/MPC（延迟/复杂）；
- 触觉/力控（API 无传感器）；
- 行走/地形 locomotion（无赛道/OOD）；
- 外部 LLM 在线 planner（单模型合规/延迟）。
