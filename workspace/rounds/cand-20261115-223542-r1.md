# 第 10 轮（新灵感循环第 1 轮；本轮灵感：「交互设计」×「扩散策略」）

> **基线**：第 9 轮 MetricVoiceGauge-ACMD（定义 532–539；引理 82–86；实验 E551–E570）。
> 本轮纪律：**交互契约化 + 生成式分块**。两个灵感分别治理 v9 的两种隐债：**交互债**（200ms 块内“盲目承诺”：人能看，却不能约定何时、以何种方式干预，显示态与真实内部态没有契约绑定）与**提议债**（块生成靠 64 条 MPC 采样加硬拒绝，提议器既非多模态、WCET 又贴死 12ms，且“生成质量”与“安全”在叙事上纠缠不清）。
> 关键分解：**提议（propose）与处置（dispose）彻底分离**——扩散策略只负责提出“更可能被接受、且带多模态结构”的候选块；安全仍只由 v9 的证书过滤与中止点集决定。交互设计只负责把“承诺”变成“可协商、可预期、可中断、可恢复”的契约，**不进入安全证明**。任一新增模块失效 ⇒ 注入中立元，严格退回 v9（引理 91/92）。

## 0. 直觉与动机

**灵感 1（交互设计 → 把 200ms 块承诺变成可协商契约）**
直觉：v9 的分块执行给机器人一个 200ms 的“承诺窗口”：一旦开始执行 a^{1:K}，人只能在一旁看。交互设计提醒我们，界面不是事后贴上去的显示器，而是一条有延迟、有一致性、有可恢复性约束的**控制通道**。核心创新：**交互契约经纪人（Interaction Contract Broker, ICB）**，把人提升为一等契约主体：交互契约 ι_h=(O_h, H_f, C_veto, D_h, R_rec) 声明“人看什么、提前多久看、如何否决、多久内必须被服务、中断后如何恢复”。三个可检验性质：
- **(a) 前瞻性（feedforward）**：块在执行前以 5Hz 预览，人获得 H_f=K_eff·Δt 的可预测时域；按直接操纵的 100ms 感知阈值，要求 H_f≥H_min=100ms，否则把块长上限压到满足为止。
- **(b) 一致性（consistency）**：显示模式是内部契约/中立元状态的**投影** Φ，禁止“静默退化”（引理 89）；这是交互设计里的“系统状态可见性”在安全系统上的强形式。
- **(c) 可中断性（interruptibility）**：否决在截止期 D_h 内必被服务，复用 v9 中止点 p* 完成安全停驻（引理 90），并提供恢复/回滚入口 R_rec。
渐进披露（progressive disclosure）：5Hz 只给人看“意图标签 + 轨迹包络 + 中止点 + 置信度 + 模式集”，细节按需展开，避免把 14 个 IP 的内部量一股脑倒给操作员。

**灵感 2（扩散策略 → 任意时间、多模态的块提议器）**
直觉：v9 的 AC 用 64 条 MPC 采样再拒绝，本质是“单峰提议 + 硬过滤”：提议器不表达“同一场景下存在多种合理做法”，且 12ms 固定开销无法随剩余预算伸缩。扩散策略把动作块建模为去噪生成过程：部分去噪即可给出**可用的粗块**，去噪步数 N_eff 随剩余预算伸缩（任意时间，anytime）；多次采样天然暴露**模式歧义** H_mode，正好是“何时该问人”的信号。核心创新：**扩散块生成器（DiffusionChunkGenerator, DCG）**。
关键纪律：**安全与生成质量解耦**——执行块必须通过 v9 证书过滤且拥有非空中止点集，生成器只影响**接受率与时延**，不影响碰撞保证（引理 87）。这使“换更强的生成模型”不再是安全论证的一部分，而只是性能优化；反过来，生成器被对抗污染时，系统也只是接受率下降，而不是安全下界下降。

**两灵感的交汇点（不是简单叠加）**
扩散策略的多模态制造了“选哪个模式”的决策问题；交互设计提供了“何时问人、如何让人选、来不及选怎么办”的契约框架。于是得到 **模式卡（mode card）**：当 H_mode>τ_amb 时，ICB 最多呈现 m≤3 个可读意图供人选择；若 D_h 内无响应，则在**证书有效**的候选中按期望效用取 argmax 自主执行。人择与自主不是二选一，而是同一契约下的**混合主动仲裁**（定义 543）。问人期间系统仍执行证书有效的保守块或安全停驻，因此询问不制造安全空洞（引理 92）。

## 1. 研究问题（轮次升级版）

- **Q1（提议-处置分离）**：能否把“生成器质量”完全移出安全证明，使任意（含退化/对抗）扩散提议器在证书过滤下都不降低 v9 的安全保证？接受率-时延如何随 N_eff 与采样数变化？
- **Q2（交互可服务性）**：交互契约的哪些量（H_f、D_h、预览信息量）决定“人是否来得及否决”？透明度不变式能否做到“显示即真实、退化必可见”，且不引入新的时序竞态？
- **Q3（歧义-延迟权衡）**：模式熵 H_mode 何时该触发询问？混合主动仲裁在无响应、抢答、误否决、否决风暴下如何同时保持活性与安全？

## 2. 设计原则（在 P10–P12 基础上新增 P13–P15）

**P13 提议-处置分离律（Propose-Dispose Separation, DCG）**
生成器只产生候选，安全只由处置器判定：执行集 A_t={ζ | Ĉ_t valid ∧ P_t≠∅ ∧ 各层 τ_i(t) 复核通过}。任何生成器 π 的改动只改变候选分布，不改变 A_t，故安全与 π 无关（引理 87）。生成器失败 ⇒ 回退 v9 MPC 采样器（中立元 = “调用 v9 提议器”），而不是放宽 A_t。

**P14 交互契约律（Interaction Contract, ICB）**
人是一等契约主体：ι_h=(O_h,H_f,C_veto,D_h,R_rec)。预览先于执行；否决在 D_h 内必被服务（复用 p*）；显示模式 = 内部状态投影 Φ，退化必须在一个周期内对人可见（安全硬动作抢占显示的例外必须被审计标记）。交互永不进入安全证明，只做监督增强：ICB/TP 失效 ⇒ 控制路径上是 no-op，联合关闭后精确退回 v9 无人监督行为（引理 91）。

**P15 歧义延迟律（Ambiguity Deferral, DCG×ICB）**
H_mode>τ_amb ⇒ 优先询问（最多 3 张模式卡），但只许在证书有效集合 A_t 内询问；D_h 超时 ⇒ 自主取 A_t 内期望效用最优。询问不得制造安全空洞：被询问期间仍执行证书有效的保守块或安全停驻；A_t=∅ 时直接走 K=1 的 v9 fallback，不询问。

## 3. 与基线的接口（如何退化）

- **交互非干扰**：ICB 与 TP 对控制路径只读（唯一写通道是人的否决；无否决时默认值 = 不干预），故其失效是控制上的 no-op，执行块与“同一周期没有人否决”的情形逐位相同；
- DCG 失效（去噪超时 / 分布漂移 / 对抗污染）⇒ 调用 v9 AC 的 MPC 采样器，候选集与 v9 逐位一致，等价 v9 提议；
- ICB+TP+DCG 全关 ⇒ 精确退回 v9 MetricVoiceGauge-ACMD（无人监督、MPC 提议、证书处置）；
- v9 的 AC/MW/ID 任一失效 ⇒ 沿用 v9 的 K_eff←1 / 手写网关 / 全唤醒，逐级退回 v8；
- 全部失效 ⇒ 完整退回 MetricVoiceGauge-ACMD v9 → MetricVoiceGauge-DA-SPR-Cal v8 → v7 → v6。

## 4. 预期贡献

1. **提议-处置分离**：首个把生成式策略（扩散）接入实时安全闭环、却**不把生成质量写进安全证明**的框架（引理 87）；给出“对抗生成器下安全下界不变”的可证性质；
2. **交互契约**：把“人机界面”从展示层提升为有截止期、有投影一致性、有否决可达性的契约层（引理 89/90），并明确交互的**非干扰**边界；
3. **歧义延迟**：用扩散的多模态熵驱动混合主动询问，并证明询问不制造安全空洞（引理 92）；
4. **预算-安全-交互三闭环**：E571–E590 覆盖生成器消融、任意时间 Pareto、否决时延、透明度审计、歧义校准、信任校准与端到端任务。

## 5. 本轮最大风险

**一句话**：交互通道与扩散生成共享同一个 20ms 预算，而否决权的有效性依赖操作员在 D_h 内察觉并反应——透明度不变式只保证“显示为真”，不保证“人来得及”，因此最大风险是**把安全责任转移给一个来不及干预的人（交互洗白的安全 / moral crumple zone）**，尤其当扩散策略的多模态被压缩成“看似可选、实则来不及选”的模式卡时。

# 第 10 轮产物 · 创新点清单 v10：**MetricVoiceGauge-DICE**（Diffusion-Interaction Contracted Execution）

> 背景：第 9 轮 MetricVoiceGauge-ACMD（定义 532–539；引理 82–86；实验 E551–E570）。
> 本轮灵感：「交互设计」×「扩散策略」。
> **继承纪律**：MetricVoiceGauge 九不变式（CVC-闭环、SpatialCert、RT-CVC、FaultCert、PrimitiveGraph、严格退化链、OTL、GCT、ER）全部保留；v9 的 AC/MW/ID 三模块原样继承。新组件一律为**可选增强**：DCG 只替换 AC 的“提议器”，ICB/TP 只读控制状态；任一环节不可用 ⇒ 注入中立元，交互与生成联合关闭后**逐位等价退回 v9**（引理 91），而非行为漂移。

## 0. 核心 IP 设计

| 编号 | 名称 | 类型 | 关键改进（相对 MetricVoiceGauge-ACMD v9） |
|---|---|---|---|
| IP-340–356 | v9 全部模块 | 继承 | 语义不变；AC 的块生成内部改为“DCG 提议 → v9 证书处置”，MW/ID 不变 |
| IP-357 | DiffusionChunkGenerator 扩散块生成器 | 新增核心模块 | DDIM 去噪生成动作块；N_eff 随剩余预算伸缩（任意时间）；多次采样聚类出模式集与 H_mode；可选安全引导只作为**提议偏置**，不进入安全判定 |
| IP-358 | InteractionContractBroker 交互契约经纪人 | 新增核心模块 | 交互契约 ι_h=(O_h,H_f,C_veto,D_h,R_rec)；5Hz 前瞻预览；否决在 D_h 内服务到 p*；模式卡与混合主动仲裁；渐进披露 |
| IP-359 | TransparencyProjector 透明度投影器 | 新增核心模块 | 显示模式 = 内部契约/中立元状态的投影 Φ；退化可见性审计；只读、非干扰；记录可回放的块证书溯源串（seed, N_eff, sample_id） |

**退化链声明（v10 契约化七级）：**
- Level-0：DCG 超时/漂移/被污染 ⇒ 提议器中立元 v_π^⊥ = v9 MPC 采样器，接受集 A_t 不变；
- Level-1：AC 证书失效或信任域破坏（Δ_dom ≥ τ_dom ∨ risk_SLAM ≥ τ_SLAM）⇒ K_eff ← 1，逐步执行，等价 v8/v9 决策粒度；
- Level-2：MW 失效 ⇒ 切换 v9 手写网关代码路径，等价 v9 集成方式；
- Level-3：ID 失效 ⇒ 全模块 active、归因冻结，等价 v9 全模块常开；
- Level-4：ICB/TP 失效 ⇒ 交互中立元 v_h^⊥ = “无预览、无否决”，控制路径 no-op，等价 v9 无人监督；
- Level-5：v8 的 DA/SPR/Cal 任一失效 ⇒ 中立元注入（Δ_dom≡0 / risk_SLAM≡0 / sensor_weight≡1），等价 v7；
- Level-6：全失效 ⇒ 完整退回 MetricVoiceGauge-ACMD v9 → v8 → v7 → v6。

## 1. 符号体系增量（定义 540–549）

**新增定义 540（交互契约 InteractionContract）** 人作为一等契约主体，声明
```
ι_h = (O_h, H_f, C_veto, D_h, R_rec)
O_h  = {意图标签, 轨迹包络, 中止点集 P_t, 置信度, 模式集 M_t}   # 渐进披露，5Hz
H_f  = K_eff·Δt ≥ H_min = 100ms                            # 直接操纵感知阈值
C_veto = {halt, slow, retarget(m_c)}                        # 人可发出的否决/改选命令
D_h  = 40ms                                                # 否决必须在 2 周期内被服务
R_rec = {resume, rollback(p*)}                              # 中断后的恢复语义
```
契约的有效性判据：块在**执行前**发布 L_t；否决从进入 C_veto 到被守卫轮询 ≤ Δt；否决的服务结果为 p* ∈ P_t（定义 534）或安全停驻。

**新增定义 541（前瞻可读性证书 LegibilityCertificate）**
```
L_t = (ι_tag, envelope(a^{1:K}), P_t, conf, H_f, seed, N_eff)
```
其中 envelope 是块轨迹的保守包围盒，conf 为生成器置信度（只用于排序与是否询问，不用于安全判定），(seed,N_eff,sample_id) 使任何一个已执行块可被离线重放审计。可读性得分 ℓ 定义为“操作员仅凭 L_t 正确预测接下来 K_eff 步意图”的准确率；ℓ 是**交互指标**，不计入安全证明。

**新增定义 542（模式投影与透明度不变式 ModeProjection）** 设内部状态 s_int ∈ S_int 由（各模块契约状态、ID 的 active/dormant/frozen、已注入的中立元 v^⊥、AC 的 K_eff、DCG 的 N_eff）构成，投影
```
Φ: S_int → M_human = {Normal, Degraded(k), Stopping, InteractionUnavailable}
```
满足：
- **可靠性（soundness）**：显示 m(t)=Φ(s_int(t))，显示不能声称内部不存在的模式；
- **完备性（completeness）**：任一退化事件（中立元注入、K_eff←1、休眠）在 Δ_vis≤1 个周期内对人可见；仅“安全硬动作抢占显示”允许显示滞后一个周期，且必须写入审计标记；
- **非干扰（non-interference）**：Φ 只读 s_int，写显示端口，不写控制端口。故 TP 的任意故障不改变执行块。

**新增定义 543（混合主动仲裁 MixedInitiativeArbitration）** 权威偏序：人的否决 ≻ 自主决策。规则：
1. 若 C_veto 在块执行期间到达，下一守卫周期立即服务到 ≤ 当前执行步的最大中止点 p*；
2. 若 H_mode>τ_amb 且模式数 ≤ m_max=3，发布模式卡；人若在 D_h 内选择 m_c，则执行 m_c 对应的证书有效块；
3. 若 D_h 超时无人响应，则在 A_t 内按期望效用 argmax 自主执行（默认动作恒存在，保证活性）；
4. 若 A_t=∅，不询问直接 K=1 fallback（v9 语义）。

**新增定义 544（扩散块生成器 DiffusionChunkGenerator）** 条件扩散策略以状态 s 为条件，从 x^N∼N(0,I) 经 N_eff 步确定性 DDIM 去噪得到动作块 x^0=a^{1:K}：
```
x^{n-1} = √ᾱ_{n-1}·(x^n − √(1−ᾱ_n)·ε_θ(x^n,n,s)) / √ᾱ_n
          + √(1−ᾱ_{n-1} − σ_n²)·ε_θ(x^n,n,s) + σ_n z,   σ_n=0（DDIM，可复现）
```
可选安全引导 ε_θ ← ε_θ − w·∇_a C(s,a) **只改变候选分布**，接受与否仍由定义 547 的 A_t 判定。多采样用不同种子；对样本聚类得到模式集 M_t 与 H_mode。可选时序集成（temporal ensembling）：若把相邻块的重叠动作平均，平均后的动作必须重新通过证书；不通过则整块替换而非平均，避免“平均出界”。

**新增定义 545（任意时间去噪预算 AnytimeBudget）**
```
B_gen(t) = B_dec − B_inherit − B_int(t) − B_margin
N_eff(t) = clamp( ⌊(B_gen(t) − B_guard) / Ŵ_step⌋, N_min, N_max )
```
默认 B_dec=20ms，B_inherit≈4ms，B_int≤0.5ms，B_margin=3.5ms，Ŵ_step=0.15ms，N_min=4，N_max=10，n_samples=8（最坏 8·10·0.15=12ms）。N_eff<N_min 或截止期守卫触发 ⇒ 返回最近一个已完成样本；无样本 ⇒ K=1 fallback（v9）。**质量-时延曲线不被假设为单调**：安全不依赖 N_eff 的单调性，只依赖 A_t。

**新增定义 546（模式熵与歧义延迟 ModeEntropy）** 对 n_samples 个 DDIM 样本聚类为 C 个模式，簇概率 p_c 为样本占比：
```
H_mode = −Σ_{c=1}^{C} p_c log₂ p_c
defer(t) ⇔ H_mode > τ_amb ∧ C ≥ 2 ∧ max_c p_c < 1 − δ
```
defer 只决定“是否发布模式卡”，不改变执行集；且 defer 期间必须同时持有一个证书有效的保守块或安全停驻，作为超时默认动作。

**新增定义 547（证书接受集与提议-处置分离 AcceptedSet）**
```
A_t = { ζ=(a^{1:K},Ĉ_t,P_t) | Ĉ_t valid ∧ P_t≠∅ ∧ ∀i: τ_i(t) 复核通过 }
执行块 ∈ A_t ∪ {K=1 的 v9 单步 fallback}
```
生成器（DCG 或 v9 MPC）只产生候选；从候选到执行必须经过 A_t 过滤。**A_t 的定义不引用生成器的任何质量量**（N_eff、conf、模式数均不参与），这是引理 87 的结构基础。

**新增定义 548（交互-生成联合预算 JointBudget）**
```
B_dec = B_gen + B_inherit + B_int + B_margin ≤ 20ms
B_int = B_preview + B_veto ≤ 0.5ms          # 预览渲染 ≤0.2ms + 否决轮询 ≤0.05ms + 余量
```
否决轮询在**每个 50Hz 守卫周期**执行且可抢占生成；生成在 5Hz 节拍摊还。若感知风暴导致 B_inherit 上升，先压 N_eff，再降预览频率（5Hz→2Hz），最后关预览；**永不通过放宽 A_t 来省预算**。

**新增定义 549（交互/生成中立元 NeutralElements）**
| 模块 | 中立元 v^⊥ | 等价基线 |
|---|---|---|
| DCG | v_π^⊥ = 调用 v9 AC 的 MPC 采样器 | v9 提议 |
| ICB | v_h^⊥ = 无预览、无否决（默认不干预） | v9 无人监督 |
| TP | v_tp^⊥ = 显示端口置 InteractionUnavailable，控制端口不写 | v9 无人监督 |
| 三者联合 | v_π^⊥ + v_h^⊥ + v_tp^⊥ | 精确 v9（引理 91） |

# IP-357 DiffusionChunkGenerator：只提议，不判定安全
class DiffusionChunkGenerator:
    def __init__(self, eps_theta, ddim_step, K_max=10, n_samples=8,
                 N_min=4, N_max=10, w_step_ms=0.15, tau_amb=0.5):
        self.eps_theta, self.ddim_step = eps_theta, ddim_step
        self.K_max, self.n_samples = K_max, n_samples
        self.N_min, self.N_max = N_min, N_max
        self.w_step_ms, self.tau_amb = w_step_ms, tau_amb

    def budget_steps(self, B_gen, B_guard=1.0):
        n = int((B_gen - B_guard) / self.w_step_ms)
        return max(self.N_min, min(self.N_max, n))

    def sample_modes(self, s, K, N_eff, rng):
        chunks = []
        for i in range(self.n_samples):
            x = rng.normal(size=(K, s.d_a))          # 每个样本一个种子（可复现）
            for n in reversed(range(N_eff)):
                eps = self.eps_theta(x, n, s)
                # 可选：eps -= w * grad_a C(s, a)；只偏置提议，不改变 A_t
                x = self.ddim_step(x, eps, n)
            chunks.append(x)
        modes = cluster_action_modes(chunks)          # 聚类 → 模式集 M_t
        return modes, mode_entropy(modes)

    def propose(self, s, K, B_gen, rng):
        N_eff = self.budget_steps(B_gen)
        modes, H = self.sample_modes(s, K, N_eff, rng)
        return modes, H, N_eff


# IP-358 InteractionContractBroker：只读控制 + 唯一写通道（否决）
class InteractionContractBroker:
    def __init__(self, D_h_ms=40.0, H_min_ms=100.0, m_max=3):
        self.D_h, self.H_min, self.m_max = D_h_ms, H_min_ms, m_max
        self.pending_veto = None

    def publish(self, L_t):                          # 5Hz 前瞻预览
        self.display.feedforward(L_t)                # intent, envelope, P_t, conf, modes

    def poll_veto(self, now_ms):                     # 50Hz 守卫内轮询
        v = self.input.pop_nonblocking()
        if v is not None:
            self.pending_veto = (v, now_ms)
        return self.pending_veto

    def service_veto(self, veto, chunk, k_exec, now_ms):
        v, t_v = veto
        if now_ms - t_v > self.D_h:                  # 超期：记录审计，不回滚控制语义
            self.audit.late_veto(now_ms - t_v)
        if v.kind == 'halt':
            return chunk.nearest_abort(k_exec)       # 复用定义 534 的 p*
        if v.kind == 'slow':
            return chunk.nearest_abort(k_exec, speed_cap=v.cap)
        if v.kind == 'retarget':
            return chunk.mode(v.mode_id)             # 只允许 A_t 内的模式

    def mode_cards(self, modes, certs):
        if mode_entropy(modes) <= self.tau_amb:
            return None
        return [m for m in top_modes(modes, self.m_max)
                if certs[m].valid]                   # 只对证书有效模式发卡

    def arbitrate(self, modes, certs, human_choice, waited_ms):
        if human_choice is not None:
            return human_choice                      # 人择优先
        if waited_ms >= self.D_h:
            return argmax_eu([m for m in modes if certs[m].valid])  # 默认自主
        return conservative_valid_mode(modes, certs)  # 等待期间执行保守块

    # ---- 蒸馏与透明度审计 ----

## 3. 推导

**引理 87（提议-处置分离 / 生成器安全无关性）** 对任意生成器 π（包括退化、随机、对抗污染的生成器），被执行块 ζ 必满足 ζ ∈ A_t（定义 547）或为 K=1 的 v9 fallback。v9 引理 82 的安全证明只使用两件事：(i) ζ ∈ A_t 给出的证书保守性 ĝ_min≥d_safe；(ii) P_t 非空给出的停车不变式。证明的每一步都不引用 π 的分布、N_eff、采样数或置信度。因此对任意 π，条件于“有块可执行”的碰撞概率上界与 v9 相同；π 只改变接受率、时延与模式覆盖。A_t=∅ 时退回 K=1，仍是 v9 已验证语义。∎
**推论 87.1**：对抗者污染 DCG 只能降低任务成功率（更多 fallback/停驻），不能降低安全下界；这给出一个可审计的“性能-安全分离”声明。

**引理 88（任意时间预算与 50Hz 守恒）** 由定义 545，N_eff·Ŵ_step + B_guard ≤ B_gen(t)；每个去噪步受 deadline_guard 约束（v9 引理 86），超时即返回最近完成样本；样本聚类与证书过滤 ≤B_guard。否决轮询每个守卫周期一次，可抢占生成；B_int≤0.5ms。由定义 548 分解，B_gen+B_inherit+B_int+B_margin≤20ms，故每周期 ≤ 感知 2ms + 决策 20ms，50Hz 保持；生成在 5Hz 摊还，典型利用率 ≤0.5。∎

**引理 89（透明投影的可靠性、完备性与非干扰）**
(i) 可靠性：Φ 是 s_int 的确定性函数，显示 m(t)=Φ(s_int(t))，故显示不会声称内部不存在的模式（前提是显示端口无实现缺陷，E578 审计）。
(ii) 完备性：任一退化事件在发生的周期 t 改变 s_int，TP 在 t 或 t+1 重投影；唯一例外是安全硬动作在周期内抢占，此时显示在 t+1 跟随**动作**且审计写入 hard_preempt 标记。故不存在超过一个周期的静默退化。
(iii) 非干扰：Φ 只读 s_int、只写显示端口；控制端口无 Φ 的出边。∎

**引理 90（否决可达性与截止期）** 设块在 t_p 发布 L_t，否决在 t_v≥t_p 进入 C_veto，守卫周期为 Δt。轮询在下一个守卫发生，故服务时刻 ≤ t_v+Δt；服务目标 p* 由 v9 引理 82 保证存在（P_t≠∅ 是 A_t 的成员条件）。若 D_h≥Δt，则“操作员在 t_v 按下否决”到“系统开始执行停驻”的延迟 ≤D_h。注意：本引理只保证**系统侧**截止期，不保证人的反应时间；人的反应时间是被测量的外生量（E577），也是本轮风险的来源。∎

**引理 91（交互/生成中立的逐位退化）**
(a) 交互非干扰：ICB/TP 对控制端口只读；唯一写通道否决在“无否决”时取默认值（不干预）。故同一周期内“ICB/TP 开启但无人否决”与“ICB/TP 关闭”产生逐位相同的执行块。ICB/TP 失效是控制 no-op。
(b) 生成中立元：v_π^⊥ 定义为调用 v9 AC 的 MPC 采样器，候选集与 v9 逐位一致；证书处置不变。
(c) 联合：(a)+(b) 且 v9 的 MW/ID/AC 不变 ⇒ 执行块、退化级、日志控制字段与 v9 逐位一致；仅交互事件日志不同（且可关闭）。故 v10 全关 = v9。∎

**引理 92（歧义延迟不制造安全空洞与活性）** defer 仅在 A_t 内发模式卡（定义 546/547），被询问期间执行 A_t 内的保守块或安全停驻；超时默认动作是 A_t 内的 argmax EU；A_t=∅ 时直接 K=1 fallback，不询问。因此询问只改变**偏好选择**，不改变执行集；由引理 87，安全性不变。活性：arbitrate 的四个分支均返回一个已定义动作（人择 / 超时 argmax / 保守块 / fallback），故无响应、抢答、误否决都不产生死锁。∎

## 7. 本轮最大风险

**一句话**：交互通道与扩散生成共享同一个 20ms 预算，而否决权的有效性依赖操作员在 D_h 内察觉并反应——透明度不变式只保证“显示为真”，不保证“人来得及”，因此最大风险是**把安全责任转移给一个来不及干预的人（交互洗白的安全 / moral crumple zone）**，尤其当扩散策略的多模态被压缩成“看似可选、实则来不及选”的模式卡时。
