# 第 8 轮 · TRACE：把 6D 相对位姿做成可验证的情节记忆，用事件触发检索与纠错

> 检索/复核日期：**2026-10-26（UTC）**。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。
>
> 轮次说明：`research.md` 已延续到第 7 轮，本轮按状态文件续为 **第 8 轮**（若按本次会话计数，则是第 1 轮）；不推倒第 7 轮的 PILOT-GPR，而是在它上面换主武器。
>
> 本轮三个灵感词：**记忆检索、事件相机、6D 位姿估计**。

**先给主判断**：UniBot 的下一层瓶颈不是“看懂语言”，而是**记住并验证物体在度量空间里的状态**。头部模型都在做更强的语义与动作先验，但公开瓶颈高度一致：开环 chunk、单帧输入、无对象级记忆、无步骤验证、无时间预算恢复。32 个任务里，计数、顺序、颜色、遮挡、撤销、动态传送带和终局放置同时存在；这正好是“记忆检索 + 事件 + 6D 位姿”的交集。**TRACE 的赌注是：把 6D 相对位姿当作记忆的索引和步骤谓词，把 RGB 伪事件当作稀疏写入/检索/纠错的触发器，把成功优先的时间预算当作控制器；三者不是外挂，而是一个闭环。**

## 0. 先纠偏：四个会被“看起来合理”带偏的事实

### 0.1 榜单不是实榜，不能用“榜首 <30%”立论

`leaderboard.html` 仍显示 Coming Soon；`leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`，8 个模型 × 32 任务的 256 条 `task_metrics` 是脚本占位（[S8]）。占位榜首 MolmoAct/DexHacker 为 29.7%/39.0，但这**不是实测排名**。可比的真机榜 Table30 V2 榜首 LoopWAM 为 **43.33%**，VLA-DM0.5 40.67%，ambase 31.67%（[S10]）。所以：
- “头部成功率不到 30%”只能当弱先验，不能当研究前提；
- 真正可用的信息是**头部模型的公开方法/瓶颈**，不是占位分数；
- 我们的目标应写成“在 320 个计分 trial 上把成功率从 p 提到 p+Δ”，而不是“超过某个占位数字”。

### 0.2 排名成功率先行，步骤分只破平

手册原文：实时榜单按 32 个任务的**总平均成功率**排序；成功率相同按**总平均步骤分**排序；仍相同则提交早者靠前（[S9]）。第 7 轮把“成功率与步骤分综合排序/步骤分优先”当作前提，需要修正：
- 任何“为了提高步骤分而牺牲成功率”的策略都是错的；
- 步骤分只在**成功无望或平局**时优化；
- 终局放置仍然是成功闸门，但它不是“步骤分大头”这么简单——它是**成功率的必要条件**。这个区分会影响 TBR（时间预算恢复）的设计：先保成功，再谈部分分。

### 0.3 Chunk 是一次性执行的，事件触发只能发生在 chunk 边界

提交接口规定：`get_action` 返回一个 `action_chunk_size` 的 chunk，评测端**从 index 0 开始按顺序执行完整个 chunk，才再次调用 `get_action`**（[S6]）。这意味着：
- 不能在 chunk 中间插入“看到滑落就立刻停”的纠正；
- 事件触发的反应时间是 `chunk_size / control_rate + 推理延迟`；
- `action_chunk_size` 是固定元数据，不能按步骤动态改；
- 事件触发纠错必须设计成**边界条件化**：当前 chunk 正常执行，下一次调用时把“惊讶/记忆/恢复上下文”注入策略。

这条约束把“事件相机”的价值从“硬件级低延迟”改写成“**稀疏状态更新 + chunk 边界重规划**”。它也是本方案与大多数 VLA 论文的分水岭：论文默认可以随时 replan，UniBot 不允许。

### 0.4 没有事件相机、没有 depth/intrinsics，但有双目和本体感觉

- 提交观测只有 4 路 RGB（左右高位 + 左右腕部，480×640）、双臂关节/EE 位姿、夹爪、下半身与语言（[S6]）；**没有 depth，也没有相机内参**。
- 但左右高位相机很可能就是 G1 的头戴双目：公开硬件资料为 60mm baseline、125° FOV、30fps（[S11]）。即使不直接给 depth，我们也可以自己做立体匹配，得到**粗糙但可用的度量深度**；1m 处 1px 视差约 10cm 误差，0.5m 处约 2.5cm——做桌面平面、物体粗定位、尺度校准足够，做毫米级插入不够。
- 腕部是单目，但距离近、分辨率高；可以用头戴双目/机器人运动学提供尺度，再用腕部做局部精修。
- 更关键的是：**EE 位姿是已知的**。抓取后物体相对夹爪固定，可以用 `T_O = T_E · T_E^O` 传播物体位姿；这给了一条几乎免费的“自监督位姿标签”通路。

所以本方案不假设事件相机，也不假设 depth；它把“事件”变成 **RGB 时序对比伪事件**，把“6D 位姿”变成 **双目粗深度 + 腕部精修 + EE 探针 + 类别先验的分层相对位姿**。

## 1. 三个词，各自钉到 UniBot 的第一性事实上

### 1.1 记忆检索：UniBot 需要的是“对象级情节记忆”，不是长视频

UniBot 的任务结构决定了记忆不是可选项：

- **计数/顺序/身份**：StackBowls 要求 red → green → blue；ArrangePlates 要求 right-to-left 的 red/green/blue；OrganizeTools 要求 right-to-left；StoreCups 要求 one by one；PickOutBatteries 要挑出 3 节电池；FruitCollection/FruitSorting 要按颜色/类别分拣。模型必须知道“已经放了几个、下一个是谁、哪个槽位被占了”。
- **遮挡/容器内部**：物品放进盒子、杯子叠起来、耳机放进充电盒、文具放进笔袋后，目标会被遮挡。仅靠当前帧的 VLA 无法知道“里面已经有什么”。
- **撤销/人干扰**：官方备注里大量是“完成后撤销”（T27 叠了第二个后拿走；T19 拉上后拉开；T14 拧开后拧回；T17 合上后打开）。这不是普通的视觉分布偏移，而是**状态从 1 变回 0**，必须有历史状态和回退逻辑。
- **动态目标**：T24 传送带上的食物在动，官方备注还会“快到了再放回起点”；模型需要预测/跟踪，不是单帧识别。

现有记忆方法的空白：
- MemoryVLA、Mem4Act、Dual-Stream 等以**潜变量记忆/视频记忆**为主，容量大、不可解释，且不直接给出度量状态；
- OCC4M 用 object-centric 4D memory，方向最接近，但依赖 depth/camera pose 和 VLM planner，不是纯 RGB VLA；
- MemBodied 用固定大小 episodic memory，适合长程导航/操作，但没有“容器系释放位姿”这种度量先验；
- OpenSPM 用 pose memory + SE(3) transfer，最接近我们的“位姿即记忆”，但它把 pose memory 接到 flow-matching 动作生成，且主要在 LIBERO-GOAL 验证。

**我们的切入点**：记忆不是“存更多帧”，而是**存对象在桌面/容器坐标系里的位姿轨迹 + 可见性 + 包含关系 + 步骤归属**。这样记忆是紧凑的、可查询的、可验证的，而且天然抗背景/位置OOD。检索也不是“按外观找相似视频”，而是**按相对位姿图找相似释放位姿/恢复片段**。

三种检索目标：
1. **当前情节状态**：`retrieve_state(o)`——这个物体上次在哪、是否被遮挡、在哪个容器里、属于哪一步；
2. **跨演示先验**：`retrieve_prior(step, scene)`——K 条演示在容器系下的释放位姿、动作先验、容差；
3. **恢复片段**：`retrieve_recovery(event, step)`——官方人干扰/滑落/撤销后的恢复动作。

三者共用同一个键：**相对位姿图 + 步骤/语言 + 运动描述子**。这是“pose-indexed memory”的核心。

### 1.2 事件相机：硬件不可加，但“变化即信息”的范式可以借

事件相机的本质不是某个具体传感器，而是：**只记录亮度变化，用稀疏事件代替稠密帧，低延迟、高动态范围、抗运动模糊**。UniBot 不允许加装事件相机，但我们可以用 RGB 时序对比构造**伪事件**：

```text
E_t^+ = 1[log I_t - log I_{t-1} > θ]
E_t^- = 1[log I_t - log I_{t-1} < -θ]
```

把 `E_t^+ / E_t^-` 累积成 2 通道事件图，作为策略的额外输入，或只用于记忆/验证模块。它便宜（每路只要 2 帧）、不需要新硬件，而且正好匹配 `obs_delta_indices` 的时序叠帧接口（[S6]）。

事件在 TRACE 里有四个明确用途：
1. **稀疏写入**：当事件密度/位姿变化超过阈值，才写 keyframe；记忆不会被稠密视频撑爆。
2. **惊讶检测**：`s_t = ||T_obs - T_pred||_Σ + λ·event_density + λ_p·predicate_mismatch`；高惊讶触发下一次 chunk 的恢复上下文。
3. **滑落/掉落检测**：释放后 0.5s 内物体位姿速度/事件密度异常 → 判定不稳定 → nudge/regrasp。
4. **人干扰检测**：人手进入画面会产生大事件爆发和新 track；检测到后暂停当前计划、重定位、回退步骤。

证据链：
- EventVLA 用稀疏视觉证据记忆（KEM）在 RoboTwin-MeM 上比 SOTA memory VLA 高约 40%，真机双臂也有效（[S27]）——它验证的是“事件式稀疏证据”而不是硬件事件相机；
- E-VLA 把 event patch 叠到 RGB 上，参数免费，低光/退化下显著提升（[S28]）；
- Event-VLA 在退化条件下 95.6%（[S29]）；
- VLA-Corrector 用视觉动态偏差检测 stale chunk，训练免费地截断/重规划（[S31]）——这正是 chunk 边界纠错的上位证据；
- 事件触发异步推理在高速动态下 +55pp、冗余推理降 100%（[S30]）。

这些工作共同说明：**事件范式的价值在“何时看/何时写/何时纠”，不一定在“必须有事件传感器”**。UniBot 的 API 恰好把“何时”限制在 chunk 边界，这反而让设计更清晰。

### 1.3 6D 位姿：不是全任务硬上，而是分层相对位姿

第 7 轮已经证明：32 个任务的终局步骤合计 1275/3200 = **39.8%**，放置/插入/堆叠/闭合类约 **59.7%**；终局步骤是 32/32 任务的成功闸门（[S2]）。但“终局放置重要”不等于“所有任务都要做完整 6D 位姿”。正确的做法是分层：

| 层级 | 对象 | 表示 | 估计方式 | 用途 |
|---|---|---|---|---|
| **A** | 刚体、不透明：碗、盘子、杯子、积木、水果、工具、盒子、架子、插头/插排 | 类别级 6D/9D 位姿 + 尺度 | 类别先验 + 单目/双目 + 多视图 + EE 探针 | 放置、堆叠、插入、检索键 |
| **B** | 关节物：相框支架、工具箱盖/锁、瓶盖、拉链、耳机盒、笔袋、注射器 | 基座位姿 + 1-DOF 关节状态 | 部件分割 + 关节先验 + 视觉跟踪 | 开合、拧、拉、锁、倒 |
| **C** | 透明/柔性：试管、水、毛巾、布袋、线缆、耳机线 | 2D/2.5D 锚点、光流、相位 | 关键点/分割/光流 + 语言相位 | 抓取点、折叠阶段、插入对准，不做完整 6D |

证据：
- OPT-Pose（CVPR 2026）统一 category-level absolute SA(3) 与 unseen-object relative SE(3)，RGB-only、camera-agnostic，预测 depth/point map/intrinsics/NOCS，在 NOCS/HouseCat6D/Omni6DPose/Toyota-Light 上 SOTA（[S32]）——这是 Tier A 的最强候选；
- SchemaPose 做 RGB category-level 9D、对称性感知（[S33]）；OneViewAll 用单参考视图做类别级位姿，92.5% ADD-0.1（[S34]）；
- F2G-Pose/RYOPO 证明类别级位姿可以实时（28/31.8 FPS），但它们用 RGB-D（[S35][S36]）；我们无 depth，只能借它们的架构/速度目标；
- Point2Pose/RRTrack 用 2D point tracker + FoundationPose 做遮挡恢复（[S37][S38]）；这个“跟踪器管身份、位姿器管几何”的思路可以直接迁移到 RGB；
- 透明物体仍然难：HFF6DoF RGB-D ADD 50.5%（[S39]），ReFlow6D 用折射做 RGB-only（[S40]）——所以 Tier C 不做完整 6D，避免把误差传进控制；
- 关节物：CAP-Net/ArtPS 做类别级 part pose（[S41]）——Tier B 只估 1-DOF，比全 6D 稳；
- OpenSPM 用 spatial pose memory + SE(3) transfer + flow matching，在 LIBERO-GOAL 85.6%（[S42]）——它证明“位姿记忆”本身有价值，但我们的差异是 RGB-only、分层、VLA 集成、验证/恢复。

**关键观点**：6D 位姿不是为了“把物体摆得毫米级准”，而是为了**给记忆一个可比较的键、给步骤一个可验证的谓词、给放置一个可迁移的目标**。位姿误差可以用协方差表达，用控制策略吸收；不需要假装每个物体都能估到毫米级。

## 2. 合成：TRACE = 位姿是状态，记忆是仓库，事件是触发器

### 2.1 一个公式

在时刻 `t`，对象级情节记忆写成：

```text
M_t = { (o_i, T_T^O_i(t), Σ_i(t), v_i(t), c_i(t), s_i(t), role_i) }
```

- `T_T^O_i`：物体 `i` 在桌面系 `T` 下的位姿；
- `Σ_i`：协方差（位姿不确定性）；
- `v_i`：可见性/遮挡概率；
- `c_i`：包含/接触关系（在哪个容器里、叠在谁上面、是否被夹住）；
- `s_i`：步骤归属（属于 SSG 的哪个节点）；
- `role_i`：目标/容器/干扰物/工具。

容器系 `C` 下的相对位姿 `T_C^O = (T_T^C)^{-1} T_T^O` 是放置/检索的规范量；它抗机器人底座/相机移动，也抗背景变化。

### 2.2 三个闭环

**写闭环（event-cued write）**：
```text
if step_changed or gripper_transition or ||ΔT_O||_Σ > τ_pose or event_density > τ_event or human_hand:
    append keyframe (T_O, Σ, event_map, gripper, predicate)
    update containment/contact graph
```
只在“状态真的变了”时写，记忆保持稀疏。

**读闭环（pose-indexed retrieval）**：
```text
query = (language, step_id, relative pose graph, motion descriptor)
state = retrieve_state(active_objects)          # 当前情节
prior = retrieve_prior(step, query, K=4..8)     # 跨演示释放位姿/动作先验
recov = retrieve_recovery(event_type, step)     # 恢复片段
```
把 `state/prior/recov` 编码成 memory/retrieval tokens，和 RGB/事件一起喂给策略。

**验证闭环（event-cued verify/recover）**：
```text
at each chunk boundary:
    surprise = ||T_obs - T_pred||_Σ + λ_e event_density + λ_p predicate_mismatch
    if surprise > τ:
        write keyframe; inject recovery context; re-anchor target
    if release and object_motion > ε within 0.5s:
        mark unstable; nudge/regrasp
```
因为 chunk 不能中断，验证只在边界发生；这也是为什么 `action_chunk_size` 要和任务动态性匹配。

### 2.3 为什么这不是“三个外挂的拼盘”

- 没有位姿，记忆只能存视频/潜变量，检索键是外观，背景一换就崩；
- 没有记忆，位姿只是当前帧的几何，无法处理遮挡、计数、撤销；
- 没有事件，记忆写入是稠密的，检索触发是固定的，无法对滑落/人干扰/传送带做出稀疏反应；
- 没有时间预算，前三个模块会在长任务上把 180s 耗尽。

TRACE 的贡献不是“又加了一个模块”，而是**把四件事压到同一个对象级状态上**：
> `pose` 是状态表示，`memory` 是状态的时间维，`event` 是状态的稀疏更新信号，`time budget` 是状态机的控制约束。

这也是它与现有工作的差异：
- vs. MemoryVLA/Mem4Act/Dual-Stream：我们不是潜变量记忆，而是**显式、度量、可验证**的对象记忆；
- vs. OCC4M：我们不依赖 depth/camera pose，且把记忆直接接到 VLA 的 chunk 生成；
- vs. OpenSPM：我们用 RGB-only 分层位姿、相对位姿图检索、事件触发纠错和时间预算，且目标是真机 32 任务；
- vs. 纯 6D 位姿论文：我们不追求全任务毫米级 6D，而是**位姿为记忆/谓词/放置服务**；
- vs. 纯检索 VLA：我们检索的是**容器系释放位姿/恢复片段**，不是整段动作轨迹。

### 2.4 与第 7 轮的关系

**保留**：
- GPR-VLA 主干 + WLA-1.0-Base 单 checkpoint；
- PGL 2D 锚点（槽位 → 锚点 → 位姿）；
- SVL settle-verify（并入 TBR 的释放验证）；
- NRB 官方备注恢复库；
- L2L 实验室数据协议（合规开关后）；
- DebugLoop 平台调试回路；
- FLEET 工程检查单。

**升级**：
- 线性 SSG → **PDAG-SSG**（偏序 DAG，支持独立子目标/撤销/乱序）；
- ICR/OPT → **PIR**（位姿索引检索，统一释放位姿/动作先验/恢复片段）；
- SVL → **TBR**（成功优先的时间预算 + 重试/换策略/继续）；
- “放置优先” → **“状态可验证优先”**：放置仍是闸门，但记忆/谓词/恢复是更底层的能力。

**新增**：
- **PEM** 对象级情节记忆；
- **RPE** 分层相对位姿 + 不确定性；
- **ECL** 伪事件 + chunk 边界纠错；
- 32 任务 × 能力矩阵（记忆/位姿层级/事件需求/终局权重/人干扰剧本）。

**修剪**：
- “步骤分优先”；
- “事件相机硬件”；
- “全任务完整 6D”；
- “长视频/潜变量大记忆”；
- “每任务 LoRA”；
- “全 32 任务高保真孪生”。

## 3. 方案轮廓（细节在产物区）

```text
语言(160条复述) ──► PDAG-SSG（步骤偏序 DAG + 谓词 + 权重 + 时长先验）
                         │  当前可执行节点集合 S_t
                         ▼
4×RGB + proprio ──► RPE（Tier A/B/C 相对位姿 + Σ）
                         │
                         ├──► PEM（对象轨迹/可见性/包含/接触/步骤）
                         │        │
                         │        ├──► PIR.retrieve_state
                         │        └──► PIR.retrieve_prior (K条演示释放位姿)
                         │
                         └──► ECL（伪事件图 / 惊讶 / 滑落 / 人干扰）
                                  │
                                  ▼
                    GPR-VLA / WLA-1.0-Base（单 checkpoint）
                    RGB + event + memory tokens + retrieval tokens + step
                                  │
                                  ▼
                    action chunk（T_a 固定，建议 8 并实测）
                                  │
                         TBR：成功优先时间预算
                         继续 / 重试 / 换策略 / 恢复 / 放弃
```

组件一句话：
- **PDAG-SSG**：把官方 `score_steps` 从线性链变成“带权重/谓词/前置条件的偏序图”，支持独立子目标、乱序执行、撤销回退；步骤分只用于破平。
- **PEM**：对象级情节记忆，存位姿轨迹 + 协方差 + 可见性 + 包含/接触 + 步骤归属；事件触发稀疏写入。
- **RPE**：分层相对位姿；A 类刚体类别级 6D，B 类关节物 1-DOF，C 类透明/柔性只做 2D/2.5D；头戴双目给粗尺度，腕部给精修，EE 给探针。
- **PIR**：位姿索引检索；键 = 相对位姿图 + 步骤/语言 + 运动描述子；值 = 容器系释放位姿统计 + 动作先验 + 恢复片段。
- **ECL**：RGB 伪事件；事件触发写入、惊讶检测、chunk 边界纠错、滑落/人干扰检测。
- **TBR**：180s 成功优先预算；按任务演示时长和节点权重分配；先保成功，再谈步骤分。

单一模型合规：PDAG/PEM/PIR/TBR 是确定性代码与数据；RPE/ECL 的学习部分（位姿头、事件编码器、记忆编码器）全部放进**唯一 checkpoint**，模型卡披露；任何模块失效都可回退到第 7 轮基线（PGL+SVL），保证优雅降级。

## 4. 可证伪的赌注

- **H1（记忆）**：在遮挡/计数/撤销任务（T27/T21/T25/T19/T17）上，PEM+PIR 比无记忆基线终局成功率高 ≥5pp；若 <2pp，记忆假设不成立。
- **H2（事件）**：在动态/人干扰任务（T24/T10/T12/T27）上，ECL 的 chunk 边界纠错把恢复成功率提高 ≥5pp；若事件触发与随机重规划无差异，事件假设不成立。
- **H3（位姿）**：RPE Tier A 的释放位姿误差中位数 <1.5cm/10°，且 PIR 迁移后的放置成功率比纯 2D 锚点高 ≥3pp；若 Tier A 误差 >3cm，退回 2D 锚点，不做 6D。
- **H4（时间预算）**：TBR 在长任务（T09/T16/T17/T31）上减少超时/无效重试，成功率 ≥3pp；若长任务成功率不升，TBR 降级为简单守卫。

这些阈值都可以用 320 个计分 trial + 调试槽做统计检验；不能只看一个任务的单次视频。

## 5. 风险与合规（先立后破）

- **位姿误差**：Tier A 仍可能被遮挡/反光/对称物体误导；用协方差 + 多视图 + EE 探针 + 置信门控；Tier C 不做 6D。
- **无内参/无 depth**：头戴双目自标定 + 机器人运动学 + 单目基础模型 + 腕部精修；所有几何量用相对位姿，避免绝对标定依赖。
- **Chunk 延迟**：`action_chunk_size` 固定；建议 8，按任务动态性在离线选；高惊讶时下一个 chunk 用“保守前几步 + 恢复上下文”。
- **记忆身份切换**：多物体/遮挡下用 appearance + 空间连续性 + 容器关系；置信不足时重新观测，不硬写。
- **检索负迁移**：键必须是相对位姿/运动，不是全局外观；K 小、上下文 dropout、置信门控；OOD 背景轴用位置/关系键。
- **单模型审计**：学习组件唯一 checkpoint；记忆/检索是数据；模型卡写清；若审计不过，去掉学习位姿头，保留 2D 锚点 + 确定性记忆。
- **外部数据/评测 rollout**：手册 2.2 之后未读到；自采/实验室数据默认 OFF；绝不用评测 rollout 训练（LoopWAM 的 deployment 自改进很诱人，但可能是 test-set contamination）。
- **时间预算**：180s 不是普遍宽裕；按任务演示时长设预算，长任务限制重试次数，保留终局验证时间。
- **统计噪声**：320 trials，p≈0.3 时 SE≈2.56pp；按 task 做 cluster bootstrap，配对种子；+3pp 才约 1.2 SE，不能拿单次调试当结论。

## 2. 问题定义与设计需求

### 2.1 形式化

把每个 episode 看成部分可观测马尔可夫决策过程：

```text
状态 x_t = ( {T_T^O_i}, containment, contact, step_set, human_activity, dynamics )
观测 o_t = (4×RGB, proprio, EE, gripper, language)
动作 a_t = chunk of joint/EE targets, length T_a
目标 g = 语言 + 官方 score_steps
成功 Φ(x_T) = 所有步骤谓词为真
```

关键：`x_t` 里的对象位姿/包含/步骤集合是**不可直接观测**的；VLA 只能从 `o_t` 推断。TRACE 显式维护 `M_t ≈ x_t`，并把 `M_t` 作为策略的条件。

### 2.2 失败模式

| # | 失败模式 | 典型任务 | 现有 VLA 的缺口 | TRACE 对策 |
|---|---|---|---|---|
| M1 | 语义/目标 grounding 错（错物体/错槽位） | T21/T22/T24 | 语言→坐标弱 | PDAG + PGL 锚点 |
| M2 | 对象状态失忆（计数/顺序/遮挡） | T27/T25/T11 | 单帧/短上下文 | PEM + PIR |
| M3 | 位姿/释放点错（叠不平、插不进、倒不准） | T27/T10/T14 | 无度量释放先验 | RPE + PIR |
| M4 | 开环漂移/旧 chunk 过期 | 全部 | chunk 不能中断 | ECL 边界纠错 + TBR |
| M5 | 干扰未检测（人手/滑落/传送带） | T24/T12/T27 | 无事件/无监控 | ECL |
| M6 | 撤销未处理（状态 1→0） | T27/T19/T14/T17 | 无历史/回退 | PEM + PDAG 回退 |
| M7 | 时间预算耗尽/无效重试 | T09/T16/T17/T31 | 无时间感知 | TBR |
| M8 | 终局未验证（掉了/没到位） | 全部放置 | 无释放后检查 | TBR settle-verify |

### 2.3 为什么继续堆语义数据不够

- 33k 演示已经覆盖了语言/物体/场景，但**没有覆盖评测时的“状态序列”**：人把碗拿走、拉链拉开、插头拔起、传送带把目标移走。这些是状态转移，不是新物体。
- 头部模型的瓶颈不在“识别物体”，而在“记住/验证/恢复”；再堆语义数据对 M2/M4/M5/M6/M7 的边际收益低。
- 纯 6D 位姿论文能解决 M3 的一部分，但不解决 M2/M5/M6/M7；纯记忆论文能解决 M2，但不解决 M3/M7。TRACE 把这些失败模式压到同一个状态表示上。

### 2.4 设计需求

- **R1 对象级度量状态**：不是视频/潜变量，而是 `T_T^O, Σ, visibility, containment, contact, step`。
- **R2 跨演示检索**：从 33k 里检索释放位姿/动作先验/恢复片段，键必须抗背景/位置 OOD。
- **R3 稀疏事件更新**：只在状态变化时写/查/纠，控制延迟与记忆容量。
- **R4 chunk 边界反应**：尊重“整 chunk 执行”的接口；用 `action_chunk_size` 和“保守前几步”吸收延迟。
- **R5 成功优先时间预算**：先保成功，再谈步骤分；按任务/节点分配 180s。
- **R6 单 checkpoint + 优雅降级**：学习组件唯一；任何模块失效可退回第 7 轮基线。
- **R7 纯 RGB、无 depth/内参**：用头戴双目、腕部近景、EE 探针、类别先验和相对位姿。

### 3.2 PDAG-SSG：评分步骤偏序图

**输入**：`info.json` 的 `score_steps`（32 任务已公开，[S2]）+ 5 条英文复述 + 任务描述。

**节点**：
```text
v_i = (id, weight, instruction, target_obj, container, action_type,
       predicate, duration_prior, preconditions, optional_order)
```

**边**：
- 物理/逻辑前置：`v_i → v_j` 若 `v_j` 需要 `v_i` 的结果；
- 语言顺序：若指令明确 red→green→blue / right-to-left / one by one，则加全序；
- 独立子目标：无路径的节点可并行/乱序（如 3 个水果、4 个工具、3 节电池）；
- 撤销边：人干扰/失败时，`v_i` 的谓词从 1→0，标记 dirty 并回退。

**谓词**（示例）：
```text
grasped(o), in(o,c), on(o1,o2), upright(o), inserted(o,slot),
closed(zipper), locked(lock), contains(c,o), clear(table),
count(c,n), stacked(o1,o2), poured(liquid,c)
```
谓词由三部分组成：学习谓词头（视觉）、几何检查（位姿/包含）、事件检查（接触/稳定）。三者投票，避免单一误判。

**调度**：
```text
S_t = { v_i | preconditions(v_i) ⊆ done }        # 当前可执行
choose v* = argmax_{v∈S_t}  w_v · P_success(v) / E_time(v)
subject to  time_left > R_t(v) + reserve
```
成功优先：`P_success` 是主项；`w_v` 只在平局/成功无望时用于步骤分。独立节点失败时可跳过先做别的，但最终成功仍需全部完成；跳过只用于争取部分分/等待恢复。

**与第 7 轮线性 SSG 的差异**：
- 不再假设官方步骤顺序就是执行顺序；
- 支持乱序/并行/撤销；
- 把 `s_t` 从标量变成完成集合，鲁棒性更高；
- 给 PIR 提供“当前节点 + 完成集合”作为检索键。

**例子 T27 StackBowls**：
```text
v1: place bowl1 in middle (30)
v2: stack bowl2 onto bowl1 (30)   [requires v1]
v3: stack bowl3 onto bowl2 (40)   [requires v2]
人干扰 human_4: 叠了第二个之后拿走第二个 → 谓词 on(bowl2,bowl1)=0
→ v2 dirty；v3 不可执行；回退到 v2；PEM 保留 bowl2 的最后位姿
```
**例子 T21 ArrangePlates**：
```text
语言约束：right-to-left, red→green→blue
v1: red plate → rightmost (30)
v2: green plate → middle (30)   [requires v1? 语言顺序]
v3: blue plate → leftmost (40)  [requires v2]
```
这里语言顺序是硬约束；如果没有语言顺序，三个放置可以乱序。

### 3.3 PEM：对象级情节记忆

**状态模式**：
```text
Track {
  id, category, appearance_embedding,
  T_T_O, Sigma_T_O,             # 桌面系位姿 + 协方差
  T_C_O,                        # 容器系相对位姿（若有容器）
  visibility,                   # 0..1
  containment,                  # container_id or null
  contact,                      # {on, in, held_by, touching}
  step_id, role,                # target/container/distractor/tool
  keyframes: [(t, T, Sigma, event_map, gripper, predicate)]
}
```

**坐标系**：
- `B`：机器人 base；
- `T`：桌面系（重力对齐；原点可取桌面上一次标定的参考点）；
- `C`：容器/架子系（canonical axes）；
- `O`：物体；
- `E`：EE。
相对量 `T_C^O`、`T_T^C`、`T_E^O` 是记忆/检索的核心；绝对量只用于控制。

**写策略**：
```text
if step_changed or gripper_transition or ||ΔT_O||_Σ > τ_pose
   or event_density > τ_event or human_hand_detected or predicate_flip:
       append keyframe
       update containment/contact
```
- 遮挡时：`visibility↓`，用常速度/支撑关系预测，不删除 track；
- 重新观测时：因子图/卡尔曼更新；身份歧义时用 appearance + 空间连续性 + 容器关系；
- 容量：每 episode 最多 32 个 track × 8 个 keyframe；老 keyframe 压缩成位姿/事件摘要，不存视频。

**读策略**：
```text
get_state(o) -> (T, Sigma, visibility, containment, contact, step)
get_history(o, window) -> keyframes
get_containment(c) -> {objects}
count(c) -> n
```
**包含/接触图**是计数与顺序的关键：`contains(box, phone)`、`on(bowl3,bowl2)`、`in(cup, rack_slot)`。它比纯位姿更稳，因为位姿可以错几厘米，但“在不在容器里”是离散的。

**为什么是情节记忆而不是长视频**：UniBot episode 只有 2–5 步、6–80s；需要的是“这个 episode 的对象状态”，不是跨小时视频理解。PEM 的容量小、可解释、可验证，适合 320 trial 的实时评测。

### 3.4 RPE：分层相对位姿与不确定性

**Tier A：刚体类别级 6D/9D**
- 对象：碗、盘子、杯子、积木、水果、工具、盒子、架子、插头/插排。
- 表示：`T_C^O`（或 `T_T^O`）+ 尺度 + 对称性标记。
- 估计：
  1. 头戴双目做粗深度/点云，拟合桌面平面，得到 `T_T`；
  2. 类别先验（OPT-Pose/SchemaPose/OneViewAll 类）给 NOCS/9D 候选；
  3. 腕部近景做局部精修；
  4. 多视图/多帧因子图融合，输出 `Σ`；
  5. 置信不足时，EE 探针（移动到物体附近，用接触/夹爪开度/本体感觉） refine。
- 证据：OPT-Pose RGB-only/ camera-agnostic [S32]；SchemaPose 9D [S33]；OneViewAll 单参考视图 [S34]；F2G/RYOPO 实时性目标 [S35][S36]。

**Tier B：关节物**
- 对象：相框支架、工具箱盖/锁、瓶盖、拉链、耳机盒、笔袋、注射器。
- 表示：基座位姿 `T_C^B` + 1-DOF 关节状态 `q`（开度/角度）。
- 估计：部件分割 + 关节先验 + 视觉跟踪；不估完整 6D 链。
- 证据：CAP-Net/ArtPS 类别级 part pose [S41]；拉链/瓶盖用 2D 关键点 + 相位更稳。

**Tier C：透明/柔性**
- 对象：试管、水、毛巾、布袋、线缆、耳机线。
- 表示：2D/2.5D 锚点、光流、折叠相位；不做完整 6D。
- 估计：关键点/分割/光流 + 语言相位（如“fold in half”）；用抓取点/放置点而非物体中心位姿。
- 证据：透明物体 HFF6DoF RGB-D ADD 50.5% [S39]，ReFlow6D RGB-only [S40]；仍难，故回退。

**不确定性**：
```text
Sigma = diag(sigma_xyz^2, sigma_rot^2) + 跨视图协方差
if sigma < tau1: 直接位姿目标
elif sigma < tau2: 视觉伺服 + 慢速
else: 2D 锚点/EE 探针/重观测
```
协方差不是装饰：它决定 PIR 是否可信、TBR 是否重试、控制是否慢速。

**无内参的工程解法**：
1. 头戴双目：用 G1 公开的 60mm baseline/125° FOV 做初始内参，在线用对极几何/基础矩阵自标定；双目匹配得到粗深度；
2. 机器人运动学：EE 位姿 + 关节角提供尺度/平面先验；
3. 单目基础模型：MoGe/Depth Anything/VGGT 类给相对深度/点图，用 EE/双目尺度对齐；
4. 腕部：用已知夹爪宽度/物体类别尺寸做尺度；
5. 所有控制量用相对位姿，减少绝对标定依赖。

**抓取相对位姿传播（关键自监督）**：
```text
抓取时刻：T_E^O ≈ 由视觉估计（或类别先验）
搬运期间：T_T^O(t) = T_T^E(t) · T_E^O
释放后：用视觉更新 T_T^O，并写入 PEM
```
这给 RPE 提供了大量免费标签：搬运段的物体位姿由 EE 位姿直接传播；抓取/释放时刻用视觉校正。它也是 PEM 在遮挡期预测的基础。

### 3.5 PIR：位姿索引检索

**库**：33k 演示 → 按 PDAG 步骤切段（抓取段、搬运段、释放段、闭合/插入段、恢复段）。每段 1–3s。

**键**：
```text
key = [
  language_embedding(5 paraphrases),
  step_id / action_type,
  relative_pose_graph: {T_C^O, T_T^C, T_E^O, pairwise distances},
  motion_descriptor: EE velocity / optical flow / gripper state,
  category_ids: object/container
]
```
不是全局外观；背景/位置变化时键仍然可比。

**值**：
```text
value = {
  release_pose: T_C^O at release (or T_C^E),
  action_prior: EE delta / joint trajectory summary,
  outcome: success/failure/recovery,
  duration,
  uncertainty
}
```

**检索**：
- HNSW/FAISS，K=4–8；先按 category/step 过滤，再按 pose graph + motion 排序；
- 释放位姿用几何中位数/弦均值 + 协方差；离散度大 → 视觉伺服；离散度小 → 直接执行；
- 恢复片段：键加 `event_type`（human_move/undo/slip/hand_enter）与当前谓词状态；值 = 恢复动作序列/重试策略。

**为什么用位姿图而不是视觉嵌入**：
- 背景轴/位置轴是官方泛化轴；视觉嵌入会被背景/位置主导；
- 位姿图是关系量，天然抗这些变化；
- 与 RPE/PEM 共用表示，检索结果可直接变成控制目标。

**延迟**：离线编码；在线 HNSW <5ms；K 小；p99 目标 <30ms（不含策略前向）。如果超预算，降 K/降维/预取。

### 3.6 ECL：RGB 伪事件与 chunk 边界纠错

**伪事件**：
```python
# 灰度、log 强度、短窗累积
g = log(gray(I) + 1)
e_on  = clip(g[t] - g[t-1], 0, None) > theta
e_off = clip(g[t-1] - g[t], 0, None) > theta
E = stack([e_on, e_off])  # 2×H×W，可再堆 2-3 帧
```
用 `obs_delta_indices` 请求 `[-1, 0]`（或 `[-2,-1,0]`）的相机帧；事件图送入小 CNN/与 RGB token 相加。训练时可用合成事件（E2VID 类）或真实帧差，推理时用真实帧差，保持同分布。

**惊讶分数**：
```text
T_pred = predict_next_pose(PEM.last_keyframe, last_action)
s = ||T_obs - T_pred||_Sigma^2
  + lambda_e * event_density
  + lambda_p * predicate_mismatch
  + lambda_h * human_hand_score
```
- 阈值 `tau_s` 由离线验证集校准（按任务/层级）；
- `s > tau_s` → 写 keyframe、把“恢复 token/重新锚定目标”注入下一个 chunk；
- `s` 低 → 正常继续，不浪费算力。

**Chunk 边界纠错**：
```text
at get_action(obs):
    update PEM/RPE/ECL
    s = surprise(obs)
    ctx = PIR.retrieve(...)
    if s > tau_s:
        ctx += recovery_context(PIR.retrieve_recovery(...))
        target = re_anchor(PEM.last_stable_pose)
    return policy.act(obs, ctx, target, step)
```
因为评测端执行完整个 chunk，纠错只能影响下一个 chunk；高惊讶时，下一个 chunk 的前几步可以“慢速/保守”（夹爪保持、速度降低），给系统留反应时间。

**滑落/掉落**：
```text
release:
    open_gripper(slow=True)
    wait 0.5s
    if ||Delta T_O|| > eps_move or event_density > tau_fall:
        mark unstable
        if repairable: nudge
        else: regrasp
```
**人干扰**：
- 人手进入 → 事件爆发 + 新 track + 目标位姿突变；
- 触发 PDAG 回退/重定位；如果人把物体拿走，PEM 保留最后位姿并标记 `missing`；
- 恢复片段由 NRB/PIR 提供。

**Chunk size**：
- `T_a` 固定；建议 8（30Hz 下约 0.27s 执行 + 推理延迟）。
- 动态任务（T24）可选 4；长任务（T09/T16/T17/T31）可选 8–16 以降低推理开销。
- 但元数据固定，不能按任务切换；只能选一个全局值，或用“chunk 内保守前几步”模拟多速率。
- 离线用平台调试槽测 `T_a ∈ {4,8,16}` 的完成时间/成功率，选一个。

### 3.7 TBR：成功优先的时间预算恢复

**预算模型**：
```text
B = 180s
R_t = sum_{v in remaining} duration_prior(v) * factor
reserve = max(8s, 0.15 * B)          # 留给终局验证
if time_left < R_t + reserve: 进入保守模式
```
`duration_prior` 来自演示中位数/90 分位；`factor` 按任务/策略校准（1.2–2.0）。

**动作集**：
```text
continue        # 正常执行当前节点
retry_current   # 重抓/重放当前节点（有限次）
restrategy      # 换抓取点/换手/换接近方向
skip_if_independent  # 跳过独立节点，先做别的（只为部分分/等待恢复）
recover         # 用 PIR/NRB 恢复片段
abort           # 成功无望，保步骤分/避免更大损失
```
**选择**：
```text
choose a = argmax  P_success(a) * 1.0 + lambda_s * step_score(a)
subject to time_left > R_t(a) + reserve
```
`lambda_s` 很小（成功优先）；只有 `P_success` 接近 0 时才让步骤分起作用。

**重试预算**（按任务组）：
| 任务组 | 每节点重试 | 总重试 | 备注 |
|---|---:|---:|---|
| 短（HangCup/StackBowls） | 2 | 3–4 | 180s 宽裕 |
| 中（PlugCharger/PhotoFrame/ZipUp） | 1–2 | 2–3 | 插入/拉链要省 |
| 中长（Earphones/PencilCase/FoldTowel） | 1 | 2 | 阶段多 |
| 长（Toolbox/OrganizeTools） | 1 | 1–2 | 4 工具往返，易超时 |

**终局验证**：TBR 内含 SVL：
```text
release slow -> wait 0.5s -> stable? -> predicate? -> done
if unstable: nudge/regrasp (<=1) -> recheck
```
若时间不足，优先“直接放置 + 一次稳定检查”，而不是“多次精细调整”。

### 3.8 与 GPR-VLA / WLA 的接口

**输入 token**：
- RGB tokens：4 路相机（可 resize 到 240×320 给策略，腕部保留 480×640 给 RPE）；
- event tokens：2 通道伪事件 + 小 CNN；
- memory tokens：PEM 的 `T, Σ, visibility, containment, contact, step` 编码（MLP/Transformer，最多 32 个对象）；
- retrieval tokens：PIR 的 K 个 `release_pose/action_prior/outcome` 编码；
- step token：PDAG 当前节点 + 完成集合 + 时间预算；
- proprio：关节/EE/夹爪/lower_body。

**输出**：
- action chunk（EE 或 joint，二选一）；
- 辅助头：位姿残差、谓词 logits、惊讶分数、步骤完成 logits、时间预测。

**训练注入**：
- 训练时必须同步构建 PIR 库并注入检索上下文（否则推理首次见到 retrieval token 会崩）；
- 随机 dropout memory/retrieval/event，让模型学会在缺失时回退；
- 用第 7 轮 GPR-VLA 的目标残差/可逆信念作为动作头，保持连续控制。

**单 checkpoint**：
- RPE 位姿头、ECL 事件编码器、PEM 编码器、谓词头、策略全部在一个 checkpoint；
- PIR 索引、PDAG 图、TBR 是数据/代码，不是模型；模型卡披露；
- 如果审计认为位姿头是“第二模型”，则把它改成策略内部的感知 adapter，仍是一个前向图。

### 3.9 推理伪代码

```python
def reset():
    pem.clear(); pdag.reset(); tbr.reset(); ecm.reset()

def get_action(obs):
    # 1. 步骤与预算
    step = pdag.current(obs.language)
    budget = tbr.update(obs.t)

    # 2. 位姿与记忆
    poses = rpe.estimate(obs, step)          # Tier A/B/C + Sigma
    pem.update(poses, obs, step)             # event-cued write inside
    state = pem.query(step.active_objects)

    # 3. 事件与惊讶
    events = ecm.pseudo_events(obs)
    surprise = ecm.score(poses, events, step)

    # 4. 检索
    ctx = pir.retrieve(step, state, events, k=6)
    if surprise > tau_s:
        ctx += pir.retrieve_recovery(step, events, k=2)
        target = pem.last_stable_pose(step.target)
    else:
        target = ctx.release_pose

    # 5. 策略
    chunk = policy.act(obs, state, events, ctx, target, step, budget)

    # 6. 边界后处理
    if surprise > tau_s:
        chunk = guard(chunk)                 # 前几步慢速/保守
    if tbr.should_stop(obs, step):
        chunk = tbr.safe_stop(chunk)
    return chunk
```

### 3.10 优雅降级

| 失效 | 降级 |
|---|---|
| RPE 位姿置信低 | 用 PGL 2D 锚点 + 视觉伺服；不做 6D |
| PEM 身份歧义 | 只用最近 1 帧 + 2D 锚点；重新观测 |
| PIR 检索失败 | 用任务级中位数/第 7 轮 OPT 统计 |
| ECL 事件噪声 | 关闭事件 token，只用 RGB；保留滑落阈值 |
| TBR 预算误判 | 退回固定重试上限 + 总时长守卫 |
| 单模型审计 | 去掉学习位姿头/事件编码器，保留确定性记忆/检索 |

## 4. 数据引擎

### 4.1 位姿伪标签（RPE 训练）

| 来源 | 方法 | 用途 | QC |
|---|---|---|---|
| 头戴双目 | 立体匹配/三角化 + 桌面平面拟合 | 粗深度、桌面系、物体中心 | 重投影 <5px；平面 <5mm |
| 抓取相对传播 | `T_O = T_E · T_E^O`，抓取/释放时刻视觉校正 | 搬运段密集位姿 | EE 回放 <2cm |
| 类别先验 | 3D 模板/类别级 NOCS；尺度从数据统计 | Tier A 初始化 | 10% 人工抽检 |
| 多视图 | 头戴 + 腕部重投影一致性 | 精修/协方差 | 一致性 <1cm |
| EE 探针 | 移动到物体附近，用接触/夹爪开度 refine | 低置信/对称物体 | 只在调试/训练用 |
| 人工 | 少量关键帧标注 | 验证/校准 | 每任务 20–50 帧 |

**注意**：不假设评测时能加标记/棋盘格；所有标定必须用场景自身（桌面、机器人、物体类别）在线/离线完成。

### 4.2 步骤/包含/接触标签

- 步骤切分：用演示时间 + 语言相位 + DTW 对齐；PDAG 节点与段对应；
- 谓词标签：抓取（夹爪闭合 + 接触）、放置（释放 + 稳定）、包含（容器内点/射线）、堆叠（支撑面 + 位置）、闭合（拉链/盖子状态）、锁（锁舌/钥匙）；
- 包含/接触图：从 3D 关系 + 演示重建；人工抽检 10%；
- 5 复述：160 条全部映射到任务/节点；用精确匹配 + 规范化 + 嵌入兜底。

### 4.3 PIR 库

```text
segment = (task, step, start/end, camera, language, pose_graph, motion, outcome)
key = [language_emb, step_id, pose_graph, motion_desc, category_ids]
value = [release_pose, action_prior, outcome, duration, uncertainty]
```
- 每任务每步骤抽 100–300 段（不是全部 1k，先控规模）；
- 恢复段：NRB + 演示中的自然重试段；
- 索引：HNSW；离线编码；在线 K=4–8；
- 版本化：数据/模型更新时重建索引，记录 hash。

### 4.4 事件/惊讶标签

- 滑落/掉落：释放后物体位姿速度/事件密度突变；
- 人干扰：人手进入/物体被移动/撤销；
- 传送带：目标运动 vs 背景运动；
- 惊讶阈值：按任务/层级在验证集上校准，最大化 AUROC；
- 负样本：正常放置/正常搬运，避免“事件=异常”的偏置。

### 4.5 NRB：官方人干扰备注

第 7 轮表 B 的备注（[S2]）直接转成破坏→恢复对：
- T27：叠第二个后拿走 → 回退到 v2，PEM 保留 bowl2 位姿；
- T19：拉上后拉开 → 重新拉合；
- T14：拧开后拧回 → 再拧开+倒药；
- T17：合上后打开 → 重新合上；
- T24：目标快到了放回起点 → 重新跟踪/抓取；
- T10/T12：拔起/拿走 → 重定位/重插/继续；
- T02/T04/T11/T25：平移水果/盘子/底座 → 重定位。

这些备注**大概率就是 human 轴的真实剧本**（编号含义未核实）；即使不是，也是分布内高价值扰动。

### 5.1 课程

| 阶段 | 数据 | 目标 | 退出条件 |

| 0 | 真实 100% | 复现 WLA/GPR 基线 | held-out 不降 |
| 1 | +PDAG 谓词标签 | 步骤状态/谓词稳 | 谓词 F1 +5 |
| 2 | +RPE 伪标签 | Tier A 位姿可用 | 中位误差 <2cm/12° |
| 3 | +PEM/PIR 上下文 | 记忆/检索不崩 | 检索释放位姿误差 −10% |
| 4 | +ECL 事件/惊讶 | 滑落/人干扰可检测 | AUROC >0.8 |
| 5 | +TBR/SVL | 长任务不超时 | 长任务 +3pp |
| 6 | +NRB 恢复 | 撤销后可恢复 | 恢复成功率 >50% |
| 7 | 全量 + 蒸馏/量化 | 延迟达标 | p99 <100ms |

### 5.2 损失

```text
L = L_flow
  + λ1 L_pose          # 位姿/点图/NOCS，按 Tier 加权
  + λ2 L_pred          # 谓词 BCE
  + λ3 L_contain       # 包含/接触
  + λ4 L_event         # 事件重建/对比
  + λ5 L_surprise      # 惊讶/滑落/人干扰
  + λ6 L_retrieval     # 检索释放位姿/动作先验一致性
  + λ7 L_step          # 步骤完成/顺序
  + λ8 L_recover       # 恢复动作
  + λ9 L_time          # 剩余时间/超时预测
```

起始权重：`L_flow=1`；`L_pose=0.2`；`L_pred=0.2`；`L_contain=0.1`；`L_event=0.05`；`L_surprise=0.1`；`L_retrieval=0.05`；`L_step=0.2`；`L_recover=0.1`；`L_time=0.05`。按验证集调，不让辅助损失压过动作。

### 5.3 超参

- 底座：WLA-1.0-Base 6B / GPR-VLA；LoRA rank 64/alpha 128；action expert 全量或 LoRA；
- AdamW，lr 1e-4（LoRA）/2e-5（全量），cosine，warmup 3%；
- global batch 64–128；bf16；
- chunk `T_a=8`（离线比较 4/8/16）；horizon 1–2s；
- 事件编码器：小型 CNN（ResNet-18 级），与 RGB token 相加；
- PEM 编码器：2 层 Transformer，最多 32 对象 × 8 keyframe；
- 早停看真实 held-out + 轴诊断，不看仿真成功率。

### 5.4 算力

- 位姿伪标签：32 任务 × 200–300 条，8×H100 约 4–6 天；
- PIR 建库：2–3 天；
- 全课程 LoRA：2–3 周；
- 事件/惊讶训练：2–3 天；
- 蒸馏/量化：3–5 天；
- 最小可运行版：不重训，只做 PDAG+PGL+RPE（推理）+PEM（确定性）+TBR；单卡 24GB 可跑 6B 量化 + 小位姿头。

### 5.5 单模型合规

- 唯一 checkpoint 包含策略、RPE 头、ECL 编码器、PEM 编码器、谓词头；
- PIR 索引是数据；PDAG 是代码；TBR 是控制逻辑；
- 模型卡写清：输入、输出、外部数据（无）、评测数据（无）、检索库来源（官方 33k）；
- 如果审计要求“不能有第二模型”，把 RPE 改成策略内部的 adapter，不单独部署第二个服务。

## 6. 评测协议

### 6.1 离线指标

| 模块 | 指标 | 目标 |
|---|---|---|
| RPE Tier A | 平移/旋转误差；ADD/ADD-S | 中位 <1.5cm/10°；ADD<0.1d >70% |

### 6.2 本地/回放

- 用官方 held-out 演示做离线回放：注入遮挡/人干扰/滑落，测 PEM/ECL/TBR；

- 每次改动跑 32 任务 × 5 轴 × 2 的离线矩阵，出 step-level 热力图。

### 6.3 平台

- **调试槽**：优先 T27（计数/顺序/撤销）、T21（颜色/顺序）、T10（插入）、T24（动态/人干扰）、T19（undo/拉链）、T14（关节/液体）。每次大版本最多 1 槽。
- **计分跑**：W7 中期、W8 终期；若只能 1 次，W8。
- **发布门**：调试槽终局成功率 +10pp 且无回归；否则不提交计分跑。
- **Soak**：N 端口并发、状态隔离、健康检查、p99 延迟；FLEET 检查单。

### 6.4 消融

- 记忆：PEM on/off；PIR key=pose vs appearance vs language；K∈{1,2,4,8}；
- 位姿：Tier A only / A+B / A+B+C；双目 on/off；EE 探针 on/off；
- 事件：ECL on/off；惊讶阈值；chunk 边界 vs 固定周期；
- 步骤：PDAG vs 线性 SSG；谓词 on/off；
- 时间：TBR on/off；重试预算；reserve；
- 恢复：NRB on/off；官方备注 vs 随机扰动；
- Chunk：4/8/16；
- 单模型：全模块 vs 去 RPE/ECL。

- 320 trials；p≈0.3 时 SE≈2.56pp；

- 不看单次视频/单任务调试当结论。

### 8.1 六个押注点的详述

**I1 PDAG-SSG**
- 动机：官方 `score_steps` 已公开；成功=所有步骤；但步骤顺序不总是执行顺序（独立子目标/人干扰撤销）。
- 差异：把线性链改成带权重/谓词/前置条件的 DAG；`S_t` 是完成集合；支持乱序、并行、回退。
- 可行性：解析 JSON + 160 复述匹配 + 谓词头；CPU 图操作。
- 步骤：解析→建图→谓词标签→状态机→调试槽。
- 风险：谓词误判 → 三票（视觉/几何/事件）+ 置信门控。

**I2 PEM**
- 动机：计数/顺序/遮挡/撤销是 32 任务的结构性需求。
- 差异：显式对象位姿轨迹 + 包含/接触图；不是视频记忆/潜变量记忆。
- 可行性：RPE 提供位姿；包含/接触可从几何+演示重建；容量小。
- 步骤：schema→离线回放→在线写/读→身份管理→调试槽。
- 风险：身份切换 → appearance+空间+容器关系；置信不足不硬写。

**I3 RPE**
- 动机：终局放置是闸门；释放位姿需要度量先验；全 6D 不现实。
- 差异：Tier A/B/C；RGB-only；头戴双目粗深度；EE 探针；Σ 驱动控制。
- 可行性：OPT-Pose/SchemaPose/OneViewAll 可借；抓取相对传播给免费标签。
- 步骤：标定→伪标签→Tier A→B/C→融合→调试槽。
- 风险：透明/反光/无内参 → 回退 2D 锚点；Tier C 不做 6D。

**I4 PIR**
- 动机：33k 演示是现成少样本库；外观键抗不了背景/位置 OOD。
- 差异：键=相对位姿图+运动+步骤；值=容器系释放位姿/动作先验/恢复片段。
- 可行性：HNSW<5ms；离线编码；K 小。
- 步骤：切段→建键→建库→训练注入→延迟压测。
- 风险：负迁移 → 置信门控/上下文 dropout；透明任务回退相位检索。

**I5 ECL**
- 动机：无事件相机；chunk 不能中断；人干扰/滑落/动态需要稀疏触发。
- 差异：RGB 伪事件 + 惊讶 + chunk 边界条件化；不是硬件事件相机。
- 可行性：帧差便宜；`obs_delta_indices` 支持；事件编码器小。
- 步骤：伪事件→惊讶标签→阈值→边界注入→调试槽。
- 风险：光照/噪声 → log 强度+自适应阈值；事件只做触发，不做唯一输入。

**I6 TBR**
- 动机：180s 非普遍宽裕；成功优先；长任务容易耗尽预算。
- 差异：任务/节点预算 + 重试/换策略/恢复 + reserve；步骤分只破平。
- 可行性：演示时长可估；确定性控制；SVL 可复用。
- 步骤：预算模型→动作集→重试表→调试槽→计分跑。
- 风险：预算误判 → 在线校准+总时长守卫；长任务限重试。
