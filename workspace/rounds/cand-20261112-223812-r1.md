# 第 1 轮（本轮灵感循环）· 以结构换参数、以结构换隐私：轻量化结构 × 隐私保护下的 UniBot 策略

> **起点是上一循环沉淀的 v2（UIP-01′~15：Gazebo × 实时性 × 模块化）。本轮不是再加一层模块，而是换一个更省的“表示基座”。** 一句话主张：**分数只由每个任务 ≤5 个有序计分步决定；既然策略真正需要知道的只是“哪一步完成/被撤回”，就不该保存、传输、反复编码整段像素历史。把状态压成“最小充分进展状态”，可以同时得到速度、泛化与隐私。** 结构是最好的压缩器，也是最好的去标识器。

---

## 0. 先给直觉：为什么“轻量”与“隐私”在本题里是同一条路

1. **计分结构极端低维。** 32 个任务每个只有 2–5 个计分点（50/50、30/30/40、25×4、20×5），合计 100 分。一个 episode 的任务相关自由度其实只有“几个物体、几个相对位姿、几个接触/开合状态”。**用整段 480×640×3 的像素历史去承载这么低维的状态，是数量级上的浪费。**
2. **最有效的轻量化不是“把大模型压小”，而是“改变表示”。** 量化/剪枝/蒸馏是把同一个函数压小；而**用几何谓词、物体中心槽、技能图去替代像素历史与单体大模型**，是把“需要学的东西”变少。前者省 FLOPs，后者省**信息**、省**数据**、也省**延迟暴露面**。
3. **隐私保护在本题里不是附加项，而是三件已存在的硬约束的交集。** ① 接口明说“只声明模型所需的最小必要观测子集”（README §2），这就是数据最小化；② 背景/身份不变性恰好是“背景泛化”轴的核心；③ N 端口必须状态隔离（README §5），这既是正确性也是“不跨 episode 泄漏”。**隐私、泛化、实时、合规，在本题里同向。**

**核心洞察：** 一个“只保留任务进度”的最小充分状态，天然比原始像素更轻、更不包含身份/背景信息、也更容易跨背景泛化。**轻量化和隐私保护不是 trade-off，而是同一个信息瓶颈的两个投影。**

**两条本轮最强的推论：**

- **R1（隐私入口是规则级的）**：既然“只发送声明过的键”是评测端行为，那么**观测最小化不是训练技巧，而是部署时的硬旋钮**；它同时降低带宽、延迟暴露面与敏感数据外流。
- **R2（几何入口是物理级的）**：头部立体已校正，**米制深度不需要学习**；用“几何/谓词”替代“外观/像素历史”在物理上可行，且天然去标识。腕部无深度是缺口，但可用头部点云 + 本体位姿 + 单目腕部局部特征补足。

## 2. 严谨定义：把“轻量 + 隐私”写成一个信息瓶颈问题

### 2.1 最小充分进展状态（MIPS, Minimal Invariant Progress State）

设任务 τ 的场景真值为 \(X_t\)（物体 6D 位姿、接触、开合角、容器状态、夹爪状态等），计分步为 \(s_1,\dots,s_n\)，权重 \(w_j\)，\(\sum_j w_j=100\)。定义**计分谓词** \(\phi_j: X_t \to [0,1]\)，以及**进展向量**

\[
p_t = \phi(X_t) = (\phi_1(X_t),\dots,\phi_n(X_t)), \qquad n\le 5.
\]

策略从观测 \(o_t\) 编码出状态 \(\sigma_t = e_\theta(o_t)\)。称 \(\sigma\) 在分布 \(\mathcal D\) 上**进展充分**，若

\[
H(p_t \mid \sigma_t) \le \epsilon,
\]

即 \(\sigma\) 不丢失预测计分谓词所需的信息。称 \(\sigma\) **最小充分**，若它是对任何其他充分统计量的函数（在双射意义下）。我们进一步要求**轻量预算**：

\[
|\mathrm{quant}(\sigma_t)| \le B \ \text{bits}, \qquad \mathrm{FLOPs}(e_\theta) \le F.
\]

**直觉**：\(p_t\) 只有 ≤5 维，因此一个几百比特的谓词/相对位姿向量就可能是充分的；整段图像历史是不必要的。

### 2.2 隐私：属性泄漏而不是“形式化 DP”

设敏感属性 \(A\) 取有限集合（人脸/人是否存在、房间/背景类别、光照、屏幕内容、演示者身份等）。定义**经验泄漏**

\[
\mathrm{Leak}_A(e) = \sup_{g}\Big(\Pr[g(e(o))=A]-\max_a \Pr[A=a]\Big),
\]

即任意探针 \(g\) 相对多数类基线能多识别出多少。它不是形式化差分隐私；在单队离线赛题里，形式化 DP 既无审计方也无收益，**我们只主张可测的属性隐私**。

### 2.3 统一目标：隐私约束的信息瓶颈

\[
\min_{\theta}\ \underbrace{I(\sigma;o)}_{\text{轻量}}+\lambda\underbrace{I(\sigma;A)}_{\text{隐私}}-\beta\underbrace{I(\sigma;p)}_{\text{效用}}
\quad \text{s.t.}\quad |\sigma|\le B,\ \mathrm{FLOPs}\le F.
\]

\(\lambda=0,\beta\to\infty\) 退化为普通监督学习；\(\lambda>0\) 鼓励“对敏感属性不可预测”。**注意：敏感属性必须逐任务屏蔽掉任务相关属性**——例如 T04/T06 的颜色是任务语义，不能当成 nuisance 删掉。

### 2.4 因果不变性：把“背景泛化”写成干预

设环境 \(e\in\mathcal E\)（背景、光照、物体实例、干扰物）。要求编码器对**背景/身份干预**不变：

\[
\big\|e_\theta(o)-e_\theta(\mathrm{do}(o,\text{bg}\to b'))\big\|_2^2\le\delta,
\]

并采用 IRM 式风险不变：

\[
\min_\theta\ \max_{e\in\mathcal E}\ \mathbb E_{o\sim e}\big[\ell(\sigma_\theta(o),p)\big].
\]

在 Gazebo 里做背景/材质/光照的**受控替换**，比在真实数据里等自然多样性更可控。

### 2.5 撤回、回滚与“遗忘”

计分步 j 在 t 时刻被撤回，用带迟滞的判据：

\[
R_{j,t}=\mathbb 1\big[\phi_j(X_{t-1})\ge 1-\delta\ \wedge\ \phi_j(X_t)\le \delta\big].
\]

一旦 \(R_{j,t}=1\)，不仅要“重做”，还必须**回滚信念**：\(b_j\leftarrow 0\)，并**擦除所有由 \(b_j=1\) 派生的缓存/计划/条件偏置**（KV、技能头偏置、后续动作计划）。否则策略会“带着已完成的假设”继续跳过该步。我们称这一步为 **RUB（Rollback Unlearning of Belief）**：它借用“机器遗忘”的语言，但目的是**正确的状态恢复**。

### 2.6 观测最小化：全局背包，而不是 per-task 在线切换

`metadata` 只能在握手时声明一次，因此 \(K\)（键集）、\(m_k\)（堆叠帧数）、\(r_k\)（分辨率）是**全局**选择。定义负载

\[
P(K,m,r)=\sum_{k\in K} m_k\,c(r_k),
\]

其中 \(c(r)\) 是实测 JPEG 字节数（见 §1）。优化

\[
\min_{K,m,r}\ P(K,m,r)\quad \text{s.t.}\quad \min_{\tau\in\mathcal T}\ \mathbb E[\text{success}_\tau]\ge 1-\eta.
\]

这是一个带实测系数的多选择背包。**关键约束：不能按任务在线少传；只能在握手时决定全局集合，运行时只能选择“用不用已传的键”。**

### 2.7 端口隔离与稀疏计算

- **ZPI（零泄漏端口隔离）**：对任意端口 \(i\ne j\)，可变状态 \(M_i\cap M_j=\varnothing\)；`reset(i)` 后 \(M_i\leftarrow\varnothing\)；端口 i 的输出不得依赖端口 j 的任何信息。验收标准：**交错执行与独立执行的动作序列逐位一致**（在确定性推理下）。
- **SXG（稀疏技能图执行器）**：共享骨干 \(f_\theta\) + 技能适配器 \(\{g_s\}\) + 路由器 \(r\)，期望计算

\[
\mathbb E[C]=c_{\text{trunk}}+\sum_s \pi_s c_s\le C_{\max},
\]

采用 top-1 路由 + 置信早退，使**平均 FLOPs 不随任务数线性增长**。

## 4. 两个灵感词：直觉 → 定义 → 不做什么

### 4.1 轻量化结构

- **直觉**：不是“把 VLA 压成小 VLA”，而是**用结构替代参数**。计分结构已经告诉我们任务的骨架（≤5 步、有序、末步更大），策略就该围绕这个骨架组织：谓词状态 + 技能图 + 稀疏适配器。
- **定义**：在预算 \((B,F)\) 下，寻找最小充分的 \(\sigma=e_\theta(o)\) 与技能图 \(G=(V,E)\)，使得平均计算 \(\mathbb E[C]\le F\)、状态比特 \(\le B\)，且进展充分性 \(H(p|\sigma)\le\epsilon\)。
- **不做什么**：不做无差别的大模型蒸馏；不为了“轻”牺牲可观测的子目标；不把技能图做成 32 个独立模型（违反单模型合规的精神）。

### 4.2 隐私保护

- **直觉**：评测环境可能是办公室/家庭，观测里可能有人的手、脸、屏幕、房间布局。**最安全的隐私策略不是“加密传输”，而是“根本不采集、不持久化、不声明”**。同时，不依赖身份/背景也恰好让策略更泛化。
- **定义**：在属性集合 \(A\) 上最小化 \(\mathrm{Leak}_A(e)\)，同时保持 \(H(p|\sigma)\le\epsilon\)；属性集合必须逐任务剔除任务相关项（颜色、形状、物体类别）。
- **不做什么**：不把“隐私”做成事后脱敏的补丁；不引入外部云服务做验证（数据外流 + 合规风险）；不做形式化 DP 训练（本题无审计收益）。

## 5. 瓶颈假设（v3）

- **H1（结构充分性）**：对大多数桌面任务，≤5 个几何/接触谓词足以决定计分步；像素历史的信息冗余远大于其贡献。若成立，MIPS 能在不降成功率的前提下大幅降负载。
- **H2（隐私=不变性=泛化）**：对背景/身份不变的表征，在“背景”与“干扰物”泛化轴上更好；隐私对抗训练是**因果正则**，不是额外负担。
- **H3（撤回需要回滚）**：仅“检测到撤回后重做”不够；若策略缓存了已完成状态的计划/偏置，必须显式擦除，否则会重复跳过。RUB 是 v2 缺失的一环。
- **H4（全局观测是瓶颈）**：`metadata` 一次性锁定观测集，MINO 必须在“最坏任务”上满足成功率，因此它更像**鲁棒优化**而非平均优化；过窄的键集会封顶难任务。
- **H5（几何的盲区）**：透明/可变形/反光物体（纸杯、亚克力架、毛巾、拉链、针管）在立体深度上不可靠；必须保留“局部外观、但不落盘/不外传”的白名单回退。
- **H6（隔离是可信度的一部分）**：跨端口状态污染会同时造成错误动作与延迟异常；ZPI 是可测的正确性属性，不是“工程洁癖”。

---

## 6. 候选与合并 → v3 清单（详见产物区）

围绕两词发散 8 个草案，合并后得到 6 个新增（UIP-16~21）与 5 处升级。旗舰是 **UIP-16 MIPS × UIP-17 PACT**：前者把“记全过程”换成“记结构”，后者保证这个结构**不记住不该记的东西**；由 **UIP-18 MINO** 控制“传什么”、**UIP-19 SXG** 控制“算多少”、**UIP-20 ZPI** 控制“别串台”、**UIP-21 DDP** 控制“别留原始数据”。

## 7. 本轮最大风险（一句话）

**把“结构”当成万能压缩器：在透明/可变形/反光物体上几何谓词会失效，而 `metadata` 只能握手一次又锁死了全局观测集——轻量与隐私的收益可能以“难任务成功率封顶”为代价。**

## 1. 旗舰 A · UIP-16 MIPS + RUB（Minimal Invariant Progress State + Rollback Unlearning of Belief）

### 1.1 机制

**MIPS 的目标不是“更强的编码器”，而是“更小的充分状态”。** 每个任务只有 ≤5 个计分步，因此维护一个进展向量

\[
p_t=(\phi_1(X_t),\dots,\phi_n(X_t))\in[0,1]^n,\quad n\le5,
\]

外加少量相对位姿/接触特征；不保存整段图像历史。谓词从**头部立体点云 + 本体位姿 + 夹爪状态 + 局部腕部外观（临时）**计算。

**谓词库（可组合，不是 32 套硬编码）：**

| 谓词 | 观测来源 | 适用任务（例） | 备注 |
|---|---|---|---|
| `grasped(obj, g)` | 夹爪开合 + 腕部/头部点云到指尖距离 | 全部抓取 | 关节电流不可用，用几何近似 |
| `placed_on(a,b)` | 物体 6D 位姿 + 支撑面/接触 | T01/T03/T20/T27 | 需要物体位姿 |
| `inside(a,b)` | 点云在容器体积内 + 上方无遮挡 | T02/T09/T18/T28 | 透明容器难 |
| `inserted(plug,port,d)` | 轴线对齐 + 插入深度 + 接触 | T10/T26 | 细接触，需 480p 头/腕 |
| `articulated(q,θ)` | 关键点/关节角（盖、拉链、锁） | T12/T14/T17/T19/T31 | 可变形/反光难 |
| `stacked(a,b)` | 相对位姿 + 接触 | T20/T27 | 稳定 |
| `sorted(color/class)` | 颜色/类别（任务相关外观） | T04/T06/T22/T24 | 外观是语义，不是 nuisance |
| `poured(liquid)` | 容器倾角 + 液面/流动 | T14/T32 | 最难，需腕部外观/光流 |
| `folded(cloth)` | 布料关键点/折痕 | T16 | 最难，需外观回退 |

**RUB（回滚遗忘）**：v2 的撤回检测只做“重做”，但策略可能缓存了“该步已完成”的计划/偏置，导致它继续跳过。RUB 在检测到 \(R_{j,t}=1\) 时：

1. 令信念 \(b_j\leftarrow0\)；
2. **擦除**由 \(b_j=1\) 派生的计划缓存、KV/历史、技能头偏置；
3. 写入短时“负记忆”（禁止重复刚才导致失败的同一动作）；
4. 重新执行第 j 步，而不是推进到 j+1。

### 1.2 状态更新与稀疏核验

只在**支撑集变化**时重算谓词：物体位移 > δ、夹爪进入物体邻域、或到达验证点 k。其余时刻用匀速/刚体跟踪外推。这样 MIPS 的平均计算远低于“每帧全量重建”。

```python
class MIPS:
    def __init__(self, predicates, tracker, B_bits=512):
        self.phi = predicates          # 每个任务 ≤5 个谓词
        self.tracker = tracker         # 物体槽 + 6D 跟踪
        self.b = [0]*len(predicates)   # 完成信念
        self.p = [0.0]*len(predicates) # 连续进展
        self.cache = {}                # 由 b_j=1 派生的计划/KV
        self.neg = {}                  # 短时负记忆

    def update(self, obs, k):
        if not self._support_changed(obs) and not k:
            return self._extrapolate()
        X = self.perceive(obs)         # 头部立体点云 + 本体 + 腕部局部
        for j, f in enumerate(self.phi):
            pj = f(X)
            if self.b[j] and pj < 0.1:         # 迟滞判撤回
                self.rollback(j)
            self.p[j] = pj
        return self.p

    def rollback(self, j):
        self.b[j] = 0
        self.cache.pop(j, None)        # RUB: 擦除已完成假设
        self.neg[j] = self.last_action # 短时负记忆
        self.redo = j

    def commit(self, j):
        self.b[j] = 1
```

### 1.3 为什么它是“轻量”的

- **状态比特**：≤5 个谓词 + 5 个相对位姿（每个 6 DoF，量化到 1 mm/0.5°）= 约 **200–600 bit**，对比图像历史每帧 49–81 KB（≈ 400–650 kbit）。
- **传输**：MIPS 本身不上传；它只是把“需要在本地保留的历史”从像素换成谓词，从而允许 `image_resize`/少堆叠（见 MINO）。
- **计算**：立体深度只在验证点跑（每 k 步），中间用跟踪；谓词是几何运算，CPU 可承受。

### 1.4 风险

- 透明/可变形/反光物体（T19/T20/T21/T25/T32）几何不可靠；保留**局部外观回退**：腕部单目特征只在本次调用内使用，**不落盘、不外传、不进入长期状态**。
- 误判撤回会反复重做；用 UIP-15 的置信门限、最大重做次数、迟滞窗口三重护栏。

## 2. 旗舰 B · UIP-17 PACT（Privacy-Adversarial Causal Training）

### 2.1 机制

训练一个编码器 \(e_\theta\)，把观测分成：

- **几何/进展通道** \(\sigma\)：进入长期状态，要求进展充分、对身份/背景不敏感；
- **局部外观通道** \(\zeta\)：只在当前调用内用于细接触（拉链、液面、布料），**不持久化**。

训练目标：

\[
\mathcal L=\underbrace{\mathcal L_{\text{pred}}(p,\hat p)}_{\text{效用}}
+\alpha\mathcal L_{\text{act}}(a,\hat a)
+\lambda\underbrace{\mathcal L_{\text{adv}}(A\mid \sigma)}_{\text{隐私}}
+\mu\underbrace{\mathcal L_{\text{cf}}}_{\text{因果不变}}
+\nu\|\sigma\|_1,
\]

其中 \(\mathcal L_{\text{adv}}\) 通过梯度反转层实现（让探针无法从 \(\sigma\) 预测敏感属性 \(A\)），\(\mathcal L_{\text{cf}}\) 是背景/实例/光照干预下的一致性损失。

### 2.2 敏感属性集合必须逐任务屏蔽

| 可以作为 nuisance | **不能**作为 nuisance |
|---|---|
| 房间/背景类别、光照、桌面纹理、屏幕文字、演示者身份/人脸、人手是否出现 | 任务相关颜色（T04/T06/T22 的分拣色）、物体类别/形状、相对位置、开合状态 |

否则会把任务语义一起删掉。实现上用**逐任务属性掩码**：每个任务声明自己的 \(A_\tau\)。

### 2.3 因果增强（在 Gazebo 或离线合成中做）

- 背景替换：分割前景后换桌面/墙面/光照；
- 实例替换：同类别不同纹理/尺寸（但不改任务相关颜色）；
- 人手干扰合成：插入/撤出合成人手（对应 `human_*`），用于训练“忽略身份、关注几何撤回”；
- 相机位姿/曝光抖动：模拟评测端差异。

```python
def pact_loss(e, pred_head, adv_head, batch, task_attrs):
    z = e(batch.obs)
    L_pred = ce(pred_head(z), batch.predicates)
    L_adv = ce(adv_head(grad_reverse(z, lam=1.0)), batch.attrs[task_attrs])
    z_cf = e(batch.counterfactual_obs)          # 背景/实例/光照干预
    L_cf = mse(z, z_cf)
    return L_pred + lam_adv*L_adv + mu*L_cf + nu*z.abs().mean()
```

### 2.4 如何证明“隐私真的降了”

不是嘴上说“不变”，而是**训练探针**：

- 在 \(\sigma\) 上训练背景分类器、人手/身份分类器、房间分类器；报告相对多数类的**优势** \(\mathrm{Adv}_A\)；
- 同时报告进展谓词的 F1/步骤分；
- 画 **隐私-效用 Pareto 曲线**（扫 \(\lambda\)）；
- 对照：直接从原始图像/普通编码器特征上做同样的探针。

**预期**：\(\sigma\) 上的 nuisance 探针接近随机；进展 F1 不降；背景泛化轴提升。若探针仍能预测背景，说明 \(\sigma\) 仍带外观，需要更强的瓶颈或直接改用符号几何。

## 3. UIP-18 MINO（Minimal Observation Knapsack Allocation）

### 3.1 规则约束（先钉死）

- `metadata` **握手一次**：键集 \(K\)、堆叠 \(m_k\)、分辨率 \(r_k\) 是**全局**选择，不能按任务在线切换；
- `obs_delta_indices` 的键**决定评测端实际发送什么**；未声明的键不会到达；
- `image_resize` 由评测端执行，键必须已在 `obs_delta_indices` 中；
- `observation.language` 的偏移必须是 `[0]`。

因此 MINO 是一个**全局鲁棒背包**：

\[
\min_{K,m,r}\ P(K,m,r)=\sum_{k\in K}m_k c(r_k)
\quad\text{s.t.}\quad
\min_{\tau\in\mathcal T}\ \mathbb E[\mathrm{success}_\tau]\ge 1-\eta,
\]

其中 \(c(r)\) 用 §3.2 的实测 JPEG 字节。

### 3.2 本轮实测的 JPEG 负载（q95, 4:4:4）

| 相机 | 480×640 | 320×240 | 缩放后比例 |
|---|---:|---:|---:|
| 头部（5 任务首帧均值） | **64.0 KB** | **25.2 KB** | 2.54× |
| 头部范围 | 48.7–80.5 KB | 19.1–32.0 KB | — |
| 腕部（1 任务首帧） | **36.4 KB** | **12.9 KB** | 2.82× |
| AV1 存储（粗估） | **~13–14 KB/帧** | — | — |

> 方法：从公开数据集视频解码首帧，RGB→PIL JPEG，`quality=95, subsampling=0`（4:4:4）。上线编码器若为 OpenCV/libjpeg-turbo，字节数会略有差异，但量级一致。**结论：上线负载约为存储码率的 4–6 倍，不能用 AV1 码率估延迟。**

### 3.3 三个候选全局配置

| 配置 | `obs_delta_indices`（图像部分） | 图像负载/次 | 相对 H | 适用判断 |
|---|---|---:|---:|---|
| **H（重）** | 4 相机 × 4 帧，原生 480p | 2×4×64.0 + 2×4×36.4 = **803 KB** | 1.00× | 信息最全，延迟/带宽最差 |
| **M（均衡）** | 头立体 ×1 帧 480p；腕 ×2 帧 240p | 2×64.0 + 2×2×12.9 = **180 KB** | 4.46× 更小 | 推荐默认：头保深度，腕保运动 |
| **L（轻）** | 头立体 ×1 帧 240p；腕 ×2 帧 240p | 2×25.2 + 2×2×12.9 = **102 KB** | 7.87× 更小 | 隐私/带宽最优，细接触风险 |

本体状态（`left_arm/right_arm/ee/gripper/lower_body`）很便宜：即使堆 4 帧也只有几 KB，**应当多堆状态、少堆图像**。语言 `[0]`。

> 以 \(T_a=8\)、控制频率 30 Hz 粗算，调用频率约 3.75 次/秒：H ≈ **3.0 MB/s**，M ≈ **0.67 MB/s**，L ≈ **0.38 MB/s**。这是网络+JPEG 编码的负载，不是 GPU 推理负载。

### 3.4 选择算法

1. 对每个任务，用 GSO/回放测量“去掉某个键/降分辨率”对步骤分的影响；
2. 得到每个键的**边际效用**与**边际字节**；
3. 在“最坏任务成功率 ≥ 1−η”的约束下做多选择背包（贪心 + 局部搜索即可）；
4. 真机锚点复核；若某难任务绑定（binding），保留其所需键但降其他键的堆叠。

```python
def mino_select(tasks, budget_bytes, eta=0.05):
    # items: (key, stack, resize) -> (bytes, per-task success delta)
    # constraint: min_t success_t >= 1-eta
    cfg = greedy_knapsack(tasks, budget_bytes)
    while min(success(t, cfg) for t in tasks) < 1 - eta:
        cfg = add_binding_key(cfg, argmin_task(tasks, cfg))
    return cfg
```

### 3.5 风险

- 全局键集是**一次性**的；L 配置可能封顶 T10/T19/T26/T32 等细接触任务；
- `image_resize` 在评测端有 CPU 开销，需与网络节省做权衡；
- 若评测端相机标定与数据集不一致，头立体深度会退化，需在线自标定/已知物体尺度兜底。

## 4. UIP-19 SXG（Sparse Skill-Graph eXecutor）

### 4.1 机制

- **技能图**：节点 = 抓/放/插/倒/拉链/折叠/堆叠/分拣/开合/挑取；边 = 计分步顺序。每个任务对应图中一条路径，**从计分点表直接生成**。
- **单骨干 + top-1 适配器**：全部技能共享视觉-语言骨干；每个技能一个参数高效适配器；路由器在 episode 起点由 `observation.language` + 首帧选择路径。**部署时仍是一个 checkpoint、一条前向路径**。
- **置信早退**：在自由空间/大块搬运阶段用更少的流匹配/扩散步数；在细接触阶段加步数。平均计算

\[
\mathbb E[C]=c_{\text{trunk}}+\sum_s\pi_s c_s\le C_{\max}.
\]

- **离线适配器合并**：把训练好的 top-1 适配器在部署前合并回骨干（或保留为稀疏参数），减少运行期路由开销；满足“单模型”合规解释。

### 4.2 与 v2 UIP-14 的差异

v2 是“32 任务≈10 技能头”的静态分解；SXG 增加**稀疏条件计算 + 早退 + 由计分点自动生成图**，把“模块化”从架构问题变成**计算预算问题**：任务数增加时，平均 FLOPs 不线性增加。

### 4.3 风险

- 路由错误会跨技能污染；用 soft routing + 通用回退头 + 语言优先（语言已给出任务）降低风险；
- 适配器合并后若性能下降，保留稀疏适配器但限制 top-1。

## 5. UIP-20 ZPI（Zero-leak Port Isolation）

### 5.1 机制

N 个端口共享一个只读骨干；每个端口有独立的可变状态对象：

\[
M_i=(\text{history}_i,\text{KV}_i,\text{RNG}_i,\text{belief}_i,\text{plan\_cache}_i),
\]

要求

\[
\forall i\ne j:\ M_i\cap M_j=\varnothing,\qquad
\mathrm{reset}(i):M_i\leftarrow\varnothing.
\]

- 共享批处理时，per-request mask 必须阻断跨端口注意力/状态；
- 随机数生成器按端口播种（或完全确定性），避免“端口间动作相关性”被误读为异常；
- 日志只记录端口 id、延迟、动作统计，不记录原始观测。

### 5.2 验收

- **交错测试**：把端口 A/B 的 episode 交错调用，与各自独立调用的动作序列逐位比较；差异必须为 0（确定性推理下）。
- **污染注入**：人为在 A 的 history 里写入哨兵值，检查 B 的输出是否变化；必须不变。
- **reset 测试**：重置后输出与全新进程一致。

### 5.3 为什么它同时是“隐私”和“可信度”

- 跨端口污染会把一个 episode 的观测/动作泄漏到另一个 episode（隐私），也会造成延迟抖动与动作异常（可信度）；
- README §5 明确要求状态隔离，ZPI 把这条工程建议变成**可测试的不变量**。

## 6. UIP-21 DDP（De-identified Data Pipeline）

### 6.1 原则：**只落盘派生量，不落盘原始帧**

- 训练/回放时，在线完成：立体深度 → 点云 → 物体槽 → 谓词/相对位姿；**原始帧用完即弃**；
- 需要外观回退时，使用**去标识帧**：人脸/人手检测 + 模糊/替换；屏幕文字遮挡；背景替换；
- 公开数据训练时，优先用几何/谓词监督；外观分支用合成/增强数据；
- 任何对外发布的统计只做聚合（可选 DP 噪声），不发布逐帧数据。

### 6.2 与 UIP-12 DRF 的关系

DRF 在 Gazebo 里合成“反向撤回 + 恢复”数据；DDP 保证这些数据**不含真实身份**，并且真实日志**不回流原始像素**。两者合起来：

\[
\text{合成干扰（覆盖形态）}+\text{去标识真实统计（校准分布）}.
\]

### 6.3 风险

- 去标识可能破坏任务相关细节（例如手部遮挡下的物体状态）；
- 背景替换若过于激进，会改变任务语义（例如书架/桌面本身就是任务对象）；
- 需要人工审计 + 逐任务白名单。

## 7. 关键推导与伪代码汇总

### 7.1 为什么“最小充分”能同时省算力与隐私

由数据处理不等式：若 \(\sigma=f(o)\) 是 \(o\) 的确定性函数，则

\[
I(\sigma;A)\le I(o;A),\qquad I(\sigma;p)\le I(o;p).
\]

MIPS 通过**只保留 \(p\) 的充分统计量**，在不降低 \(I(\sigma;p)\) 的前提下，尽量降低 \(I(\sigma;o)\)（从而降低 \(I(\sigma;A)\)）。这就是“轻量”和“隐私”同向的形式化理由。

### 7.2 撤回的迟滞判据

\[
R_{j,t}=\mathbb 1[\phi_j(X_{t-1})\ge1-\delta\ \wedge\ \phi_j(X_t)\le\delta].
\]

迟滞窗口 \(\delta\) 防止抖动误报；连续两帧满足才触发，进一步降低误报。

### 7.3 端到端伪代码

```python
class V3Policy:
    def __init__(self, mips, sxg, verifier, csg, K_MAX=8):
        self.mips, self.sxg, self.verifier, self.csg = mips, sxg, verifier, csg
        self.K_MAX = K_MAX

    def reset(self):
        self.mips.reset(); self.sxg.reset(); self.g = 0; self.buf = []

    def get_action(self, obs):
        p = self.mips.update(obs, self.g)
        st = self.verifier(p, self.g)          # done/ongoing/regressed
        if st == "regressed":
            self.mips.rollback(self.g)         # RUB
            self.buf = []
        if st == "done":
            self.g += 1; self.buf = []
        if not self.buf:
            k = self.sxg.pick_chunk(self.g, p) # SXG 早退/块长
            self.buf = list(self.sxg.act(obs, self.g, k))[:k]
        act = self.buf.pop(0)
        return self.csg.clip(act, self.g)      # 平滑/预算/异常护栏
```

def payload(cfg):
    b = 0
    for key, (frames, res) in cfg.items():

        b += frames * c

## 9. 合规、隐私与风险

- **单模型合规**：SXG 的所有适配器在同一个 checkpoint 内，共享一条骨干；不调用外部 VLM/云服务；训练期的对抗头在部署时丢弃。
- **数据最小化**：只在握手时声明必要键；不落盘原始帧；日志只留延迟/动作统计。
- **接口红线**：形状/dtype/token/块长严格按 README §2–§4；返回块长不得超过声明；动作统计要平滑。
- **隐私边界**：属性隐私是经验度量，不是形式化 DP；若主办方要求更严格合规，以手册为准。
- **仿真过拟合**：GSO 只做结构裁判；真机锚点不可省。
- **手册仍缺失**：5 轴中的位置/干扰物/背景细节、评测轮次/时限/控制频率仍待飞书手册公开后核实。

## 11. 本轮最大风险 & 押注

**一句话**：结构抽象可能把任务关键线索一起删掉——透明/可变形/反光物体恰恰依赖外观与细纹理，而 `metadata` 只能握手一次又锁死全局观测集，轻量/隐私的收益可能以难任务成功率封顶为代价。

**→ 押注：把 v2 的“扰动恢复闭环”重建在 MIPS × PACT 上**——MIPS 让撤回检测变便宜（谓词状态 + RUB），PACT 让它在未见背景/人为干扰下不依赖身份线索，MINO/SXG/ZPI/DDP 分别守住带宽、算力、隔离与数据合规。它同时命中“轻量化结构”和“隐私保护”，且全部落在选手 API 权限与离线算力之内。
