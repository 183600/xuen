# 第 3 轮迭代（灵感循环 v3：「边缘计算」×「动作空间」）—— 把「被撤回」变成动作空间里的逆算子，把「恢复」下沉到块边界的边缘执行层

> 承接状态文件里的 v2（UIP-01′~15）。v2 的旗舰 UIP-01′/09′ 已经把规则读对了一半：人为干扰大量是「把已完成进度撤回」，所以要在滚动验证后「重做」。但它留下两个**没有被动作层落地**的空洞：
>
> 1. **「重做」到底是一段什么动作？** v2 只写了语义上的 `regressed → redo`，没有定义在 `joint`/`ee` 动作空间里如何生成这段恢复动作。面对「拧回、翻开、拉开、拿走、挪底座」这些不同形态，同一个「重做」根本无法执行。
> 2. **「检查/恢复」在哪里算？** v2 默认每次都可以叫醒完整 VLA；但接口是**开环动作块**：评测端执行完 `T_a` 步才回传一次观测。真正能省下的不是「块内高频伺服」（接口根本不允许），而是**块边界上不调用大模型也能继续/撤销一个算子**。
>
> 本轮两个灵感词正好各补一个洞：**动作空间**把干扰从「一个需要重新分类的状态」变成「动作语法里的一个算子」，恢复 = **逆算子 + 续做**；**边缘计算**把服务拆成「慢的云端算子规划」与「快的边缘算子执行/边界恢复」，边缘不必跑完整 VLA 也能返回恰好 `T_a` 步的恢复动作。核心命题从 v2 的「检测到撤回就重做」升级为：**把撤回当作动作空间中的可逆扰动，在块边界用逆算子做最小代价恢复；不可逆的移除则止损，而不是盲目重做。**

**由事实直接推出的三个硬约束**：

1. **反应粒度 = `T_a` 个控制步**。设控制周期 `Δt`，块周期 `P = T_a·Δt`；干扰发生在块内时，最早也要到下一个块边界才可能被看到。这是接口级下界，不是算法选择。
2. **「边缘」不是机器人本体上的芯片**。选手只能控制自己的服务端；所以本轮的边缘指**选手侧的低延迟执行层**（同一台机器上的轻量算子执行器/早退头，或选手可控的近距离副本）。前者不依赖任何地理假设，是主路径；后者只在赛制允许且可探测 RTT 时作为增强。
3. **动作空间是唯一能落地恢复的通道**。验证器可以语义化，但最终必须变成 `joint` 或 `ee` 的 `(T_a, …)` 动作；恢复如果要快，就必须在动作空间里可组合、可逆、可拼接。

## 2. 两个灵感词：先直觉，再严谨定义

### 2.1 边缘计算：直觉 → 定义

**直觉。** 不要把「边缘」想成「把大模型裁小搬过去」。在 UniBot 里，真正需要快的不是「看懂整句话」，而是**在块边界上做一个很小的决定**：上一块的进度还在不在？如果被退回了，下一块应该先做哪个逆动作？这件事不需要完整 VLA，只需要一个**算子执行器**：它知道当前算子、目标物体/容器、已完成的步骤，以及动作空间的边界。云端 VLA 负责「下一步做什么算子、参数大概多少」；边缘负责「把算子编译成恰好 `T_a` 步的动作，并在边界上守住/撤销它」。这就是计算放在动作发生点附近的边缘计算。

**严谨定义。** 把策略拆成两层：
`π = (π_C, π_E)`，其中 `π_C` 是重的云端 VLA（算子规划器），`π_E` 是轻的边缘执行器（算子编译器 + 边界恢复器）。
- `π_C: (o_j, l, M_j) → σ` 输出一个**算子计划/段** `σ = (op_1, …, op_m)` 及其参数；`M_j` 是步骤账本。
- `π_E: (o_j, σ_j, A_prev) → A_j ∈ A^{T_a}` 把算子计划编译成恰好 `T_a` 步的动作块，并在检测到扰动时插入逆算子。
- 边界周期 `P = T_a·Δt`。一次边界决策的延迟
  `L = P + RTT + T_decision + T_io`，
  其中云端路径 `T_decision = T_C`，边缘路径 `T_decision = T_E`，通常 `T_E ≪ T_C`。**注意**：边缘不改变 `RTT`（除非地理上更近，且这一点未被赛制证实），它省的是 `T_C`；块内仍然没有观测，`P` 是反应粒度下界。
- 边缘路径的触发条件：`(i)` 当前算子仍在执行且进度谓词未变；`(ii)` 检测到可逆撤回且置信度足够；`(iii)` 不需要新的语义规划。否则回云端。
- 单模型合规：云端是唯一的学习策略；边缘的算子编译器是**确定性代码**，边界恢复头（若有）必须与云端**共享骨干/同权重蒸馏**，不能是第二个独立大模型。

**一句话**：边缘计算的正确用法不是「更快地重跑大模型」，而是「让大模型少被叫醒，让动作空间里的恢复在边界上本地完成」。

### 2.2 动作空间：直觉 → 定义

**直觉。** 规则里的干扰看起来是 32 种招式，但在动作空间里它们只有少数几种「语法」：把物体平移、把容器平移、把铰链/拉链/盖子/瓶盖反向拧、把已放入的东西拔出、把东西拿走、把底座挪走、把传送带上的东西放回起点。机器人本来就会这些动作；干扰只是**别人用同一套动作语法把状态往回改了一笔**。所以恢复不该是「重新理解任务再规划」，而应该是**认出那一笔是什么算子，然后执行它的逆算子**。这就像编辑文本：不是重写整篇文章，而是按一次 Ctrl+Z，再继续输入。

**严谨定义。** 设动作空间
`A = A_arm × A_hand × A_base`。
- `joint` 模式：`A_arm = R^7 × R^7`，`A_hand = R × R`，`A_base = R^7`（`pivot`）；`ee` 模式：`A_arm = SE(3) × SE(3)`（用 xyz+rpy 表示），其余相同。控制空间在握手时固定。
- 一个动作块是 `A^{T_a}`；每个键的形状恰好 `(T_a, …)`。
- **动作算子语法** `O`：每个算子 `op = (Pre, Traj, Post, Inv)`，`Pre/Post` 是物体/容器/夹爪/底座的谓词，`Traj: O → A^{τ}` 生成 `τ` 步动作轨迹，`Inv` 是逆算子（若存在）。基本算子：
  - `Reach(F, δ)`、`Grasp(F)`、`Release(F)`；
  - `MoveHeld(F, Δ)`、`RotateHeld(F, R)`；
  - `Articulate(F, θ, axis)`：开/合、拉上/拉开、拧紧/拧开、折/展开；
  - `Insert(F_obj, F_target, d)`、`Extract(F_obj, F_target)`；
  - `Place(F_obj, F_support)`、`Pick(F_obj)`；
  - `Pivot(Δθ)`（底座/腰部重对准）、`Wait()`。
- **扰动算子** `D ∈ O*`：人为干扰被建模为同一语法上的算子序列。例如 T19「拉上后拉开」`D = Articulate(zip, +θ)` 施加在已 `Articulate(zip, −θ)` 的状态上；T14「拧回」`D = Articulate(screw, −θ)`；T25「挪底座」`D = Pivot(Δθ)` 或 `MoveBase(Δ)`；T12「把锁拿走」`D = Remove(lock)`。
- **逆算子**：`MoveHeld(Δ)^{-1}=MoveHeld(−Δ)`；`RotateHeld(R)^{-1}=RotateHeld(R^{-1})`；`Articulate(θ)^{-1}=Articulate(−θ)`（对刚性铰链/拉链/螺纹；对毛巾等非刚体用「重新折叠」而非时间反演）；`Insert^{-1}=Extract`；`Place^{-1}=Pick/Extract`；`Pivot(Δθ)^{-1}=Pivot(−Δθ)`。`Remove` 在物体离开工作区时**没有逆算子**；`ResetToStart` 是 `Extract + Place(start)` 的复合。
- **可恢复性分级**：
  - `R0`：存在原地逆算子，且一个块内可完成（如拧回、拉开、翻开、合上）；
  - `R1`：逆算子存在，但物体/容器被平移/旋转，需要先**重定位帧**再续做（大多数「向左/向右/向前移动」）；
  - `R2`：逆算子存在，但物体已脱手/出界，需要**重新抓取/接近**（如拔起插头、拿下第二个碗后仍可够到）；
  - `R3`：无逆算子或预算不足（物体被拿走、损坏、不可达）→ **止损/等待**，不重做。
- **对象中心动作帧（OCAF）**：对物体/容器 `O`，设其世界位姿 `T_WO`。把世界系动作 `a_W=(Δp, ΔR, g, b)` 变换到对象系：
  `a_O = (R_WO^T Δp, R_WO^T ΔR R_WO, g, b)`。
  若扰动是刚体变换 `D_T`，则 `T_WO' = D_T T_WO`，而同一个 `a_O` 产生的**相对运动不变**。因此对 `R1` 类干扰，恢复 = 重新估计 `T_WO'` + 重放剩余算子，不需要重新学习或重新语义规划。对非刚体（毛巾），用关键点/折叠状态而不是刚体帧。
- **动作块编译（恰好 `T_a` 步）**：给定算子计划 `σ`，按顺序把每个 `Traj` 拼接/截断到 `T_a` 步；若插入逆算子，逆算子优先占用块首，剩余步数用原计划续做；逆算子超过 `T_a` 步则跨块继续，下个边界重新评估。块首与上一块末动作用**最小 jerk** 混合 `b` 步，并裁剪到关节/EE 限位。每个键都必须是 `(T_a, …)`，`meta.token` 必须携带。
- **边界状态机（5 态）**：对每个计分步 `g`，谓词 `φ_g(o)`：
  - `done`：`φ_g=1` 且置信度足够；
  - `ongoing`：`φ_g=0`，但进度信号未倒退；
  - `fail`：预算内多次尝试仍 `φ_g=0`；
  - `regressed`：历史某边界 `φ_g=1`，当前 `φ_g=0`，且可见性/置信度足够；
  - `occluded`：`φ_g` 不可评估（遮挡/出画/图像损坏）。**新增此态**：`occluded` 不触发重做，只触发等待/加密观察/回云端，避免 v2「看不见就以为被撤回」的自伤。

**一句话**：动作空间让恢复变得**可执行**；对象中心帧让「物体被挪走」变成**换一个坐标系**，而不是换一个计划。

### 2.3 为什么两个词必须一起用

动作空间回答 **what**：要执行哪个逆算子、在哪个帧里执行、是否可逆。
边缘计算回答 **where/when**：在哪个块边界、用哪一层执行、是否值得叫醒云端。
缺了动作空间，边缘只能「更快地重跑大模型」；缺了边缘，逆算子要等云端回来才算得出来。两者合起来，才形成「**云端规划算子、边缘执行/撤销算子、块边界最小代价恢复**」的闭环。

## 3. 瓶颈假设（v3）

- **H1（最高杠杆）**：30 个带 `human_*` 的任务里，大多数干扰在动作语法上是**可逆的**（平移/旋转/铰链/插入/底座），因此「逆算子 + 续做」比「盲目重做/重新语义规划」更省步数、更快、更少误动作。真正不可逆的只是少数「拿走/移除」。
- **H2**：反应延迟的主项是 `P = T_a·Δt`，不是云端推理；但**边界决策的延迟与方差**会影响 episode 的时间预算与可信度。边缘执行器能把 `T_C` 从每次边界决策中拿掉，从而在不改 `T_a` 的前提下减少延迟与抖动。
- **H3**：对象中心动作帧能把「位置泛化轴」的大部分平移/旋转干扰转化为「重定位帧 + 续做」，减少对未见位置/未见图的数据需求；但对遮挡、非刚体、移除无效，必须保留 `R3` 止损。
- **H4**：把「人活动」与「人撤回」混为一谈会过度触发。检测应至少分离：`φ` 的 1→0（撤回）、关节跟踪残差的持续偏大（被按住/打滑/物体被挪）、物体帧的刚体位移（平移/旋转）、物体消失（移除）。只有第一种/第三种进入逆算子；第四种进入止损。
- **H5**：单模型合规是硬约束。边缘执行器必须是确定性算子编译 + 共享骨干/同权重蒸馏头；独立的第二个学习策略（尤其是外部 VLM）在本轮继续封存。
- **H6**：`T_a` 是离线一次性选择，不能按阶段变。正确做法是用少量探针任务在 `T_a ∈ {1,2,4,8,16}` 上标定「反应 vs 调用开销 vs 动作平滑」的折中，然后固定。

## 1. 旗舰深潜：UIP-16 · EAR-Gov（Edge Action-space Recovery Governor）

### 1.1 直觉

v2 的 `regressed → redo` 像医生说“再治一次”，但没开药。真正的恢复动作只有几类：**把被拧回的再拧开、把被拉开的再拉上、把被翻开的再叠好、把被拔出的再插回、把被挪走的物体/容器重新定位、把被挪走的底座重新对准**。这些都是动作空间里的算子，不是新的语义任务。EAR-Gov 就是在块边界上做这件事：**先认算子，再执行逆算子；认不出/不可逆就止损。**

### 1.2 形式定义

**(a) 动作空间与块。**
`A = A_arm × A_hand × A_base`，控制空间 `c ∈ {joint, ee}` 握手固定。
`joint`: `A_arm = R^7 × R^7`，`A_hand = R × R`，`A_base = R^7`；
`ee`: `A_arm = SE(3) × SE(3)`（xyz+rpy），其余同。
动作块 `A^{T_a}`；每个键形状 `(T_a, …)`；`meta.token` 必须携带。

**(b) 算子与逆。**
`op = (Pre, Traj, Post, Inv)`。算子库见 §2。逆算子 `Inv(op)` 满足
`Post(Inv(op) ∘ op ∘ x) ⊨ Pre(op) ∧ ¬Post(op)`（在可逆域内），
即“把 `op` 刚造成的那一笔改回去”。对刚体平移/旋转/铰链/插入，逆算子存在；对 `Remove`（物体离开工作区）无逆算子。

**(c) 扰动算子与可恢复性。**
边界观测序列 `o_1, …, o_j`。对每个计分步 `g`，谓词 `φ_g(o) ∈ {0,1,⊥}`（`⊥`=不可评估）。
- `regressed_g(j)` ⇔ `∃ j'<j: φ_g(o_{j'})=1 ∧ φ_g(o_j)=0 ∧ conf ≥ θ_vis ∧ 非遮挡`。
- 由 `o_{j-1}→o_j` 的状态变化估计扰动算子 `D̂ ∈ O*`（平移/旋转/铰链/插入/移除/底座）。
- 可恢复性：
  - `R0`：`∃ Inv(D̂)` 且 `τ(Inv) ≤ T_a`；
  - `R1`：`∃ Inv(D̂)`，但需先更新物体/容器帧 `T_WO`（刚体平移/旋转）；
  - `R2`：`∃ Inv(D̂)`，但物体已脱手/出界，需 `Reach/Grasp` 重新接近；
  - `R3`：`∄ Inv(D̂)`（移除/损坏/不可达）或预算不足。
- 恢复选择：
  `ρ* = argmin_{ρ ∈ {Inv(D̂), Relocalize+Inv(D̂), Regrasp+Inv(D̂), Wait, StopLoss}} E[cost(ρ)]`
  `s.t. E[latency(ρ)] ≤ L_budget ∧ redos ≤ N_redo`。
  `R3` 时只能选 `Wait/StopLoss`，**不重做**。

**(d) 5 态边界状态机。**
`state_g ∈ {done, ongoing, fail, regressed, occluded}`。
- `done`：`φ_g=1` 且 `conf≥θ`；推进 `g`。
- `ongoing`：`φ_g=0`，无倒退证据；继续当前算子。
- `fail`：预算内多次 `ongoing` 后仍 `φ_g=0`；有界 `retry`（重抓/换姿态/换手）。
- `regressed`：`φ_g` 历史为 1、当前为 0、可见；进入逆算子选择。
- `occluded`：`φ_g=⊥`；**不重做**，只 `wait/加密观察/回云端`。这是相对 v2 四态的关键修正。

**(e) 对象中心动作帧（OCAF）。**
`T_WO` 为物体/容器世界位姿。世界动作 `a_W=(Δp,ΔR,g,b)` 与对象系动作
`a_O=(R_WO^T Δp, R_WO^T ΔR R_WO, g, b)` 等价。
若扰动是刚体 `D_T`：`T_WO' = D_T T_WO`，则**同一个 `a_O` 的相对效果不变**。因此 `R1` 恢复 = 重估 `T_WO'` + 重放剩余算子；不需要重新语义规划。非刚体（毛巾）用折叠关键点/折叠状态，不用刚体变换。

**(f) 恰好 `T_a` 步编译。**
`Compile(σ, τ=T_a) → A^{T_a}`：
1. 若 `regressed` 且 `R0/R1/R2`，把 `Inv(D̂)` 放块首；
2. 用完 `Inv` 的步数后，用剩余步数续做原算子计划；
3. 若 `Inv` 超过 `T_a`，本块全做 `Inv` 的前 `T_a` 步，下个边界继续；
4. 块首与上一块末动作做 `b` 步最小 jerk 混合；
5. 裁剪到关节/EE 限位；所有键补足 `(T_a, …)`。

**(g) 延迟与反应。**
`P = T_a·Δt`；边界决策延迟
`L = P + RTT + T_decision + T_io`。
云端路径 `T_decision=T_C`，边缘路径 `T_decision=T_E`。边缘**不能**减少 `P`，也**不能**在块内反应；它只减少 `T_decision`。因此：
`反应下界 = P + RTT + min(T_E, T_C) + T_io`。
这是本方案最重要的诚实边界。

```python
class EARPolicy:
    def __init__(self, cloud, edge_exec, ops, T_a=8,
                 conf=0.6, max_redo=2, latency_budget_ms=250):
        self.cloud, self.edge, self.ops = cloud, edge_exec, ops
        self.T_a, self.conf, self.max_redo = T_a, conf, max_redo
        self.lat_budget = latency_budget_ms

    def reset(self):
        self.cloud.reset(); self.edge.reset()
        self.g = 0                 # 当前计分步
        self.redo = 0
        self.plan = []             # 当前算子计划
        self.prev_chunk = None

    def get_action(self, obs):
        # 1) 边界验证（只在此刻有观测）
        states = self.edge.verify(obs, self.g)          # done/ongoing/fail/regressed/occluded
        st = states[self.g]

        # 2) 选择恢复/推进
        if st == "done":
            self.g += 1; self.redo = 0
        elif st == "occluded":
            return self._compile(self._hold_or_resume(obs), obs)   # 不重做
        elif st == "regressed":
            D = self.edge.infer_operator(obs, self.prev_chunk)
            rc = self.ops.recoverability(D, obs)       # R0/R1/R2/R3
            if rc == "R3" or self.redo >= self.max_redo:
                return self._compile(self._stop_loss(obs), obs)
            self.redo += 1
            self.plan = [self.ops.inverse(D)] + self._remaining_plan(obs)
        elif st == "fail":
            if self.redo < self.max_redo:
                self.redo += 1
                self.plan = [self._retry_operator(obs)] + self._remaining_plan(obs)
            else:
                return self._compile(self._stop_loss(obs), obs)

        # 3) 需要新算子/语义时叫云端；否则边缘本地续做/撤销
        if not self.plan or self.edge.needs_cloud(obs):
            self.plan = self.cloud.plan_operators(obs, self.g)

        # 4) 编译成恰好 T_a 步；边缘可完成则不必等云端
        chunk = self._compile(self.plan, obs)
        self.prev_chunk = chunk
        return chunk

    def _compile(self, plan, obs):
        return self.ops.compile_TO(plan, obs, self.T_a)  # shape (T_a, …) per key
```

```python
class OperatorLibrary:
    def inverse(self, D):
        if D.kind in ("MoveHeld", "RotateHeld", "Articulate", "Pivot"):
            return D.inverted()
        if D.kind == "Insert":
            return Op("Extract", D.obj, D.target)
        if D.kind == "Place":
            return Op("Pick", D.obj)
        raise NoInverse(D)          # Remove/ResetToStart 走复合或止损

    def recoverability(self, D, obs):
        if D.kind == "Remove" and not obs.object_reachable(D.obj):
            return "R3"
        if D.kind in ("MoveHeld", "RotateHeld", "Articulate", "Pivot"):
            return "R0" if not D.needs_relocalize else "R1"
        if D.kind in ("Insert", "Place"):
            return "R1" if obs.holds(D.obj) else "R2"
        return "R3"
```

## 2. UIP-17 · AOG（动作算子语法与逆算子表）

### 2.1 算子库

| 算子 | 语义 | 前置 | 后置 | 逆算子 |
|---|---|---|---|---|
| `Reach(F, δ)` | 末端到帧 `F` 的偏移位姿 | 可见/可达 | 末端在 `δ` | `Retreat` |
| `Grasp(F)` | 在物体帧闭合夹爪 | 末端到位 | `held(F)` | `Release(F)` |
| `Release(F)` | 张开夹爪 | `held(F)` | `¬held` | `Grasp(F)` |
| `MoveHeld(F, Δ)` | 持物平移 | `held(F)` | 物体位移 `Δ` | `MoveHeld(F, −Δ)` |
| `RotateHeld(F, R)` | 持物旋转 | `held(F)` | 物体旋转 `R` | `RotateHeld(F, R⁻¹)` |
| `Articulate(F, θ, axis)` | 开/合、拉/拉、拧/拧、折/展 | 铰链/拉链/螺纹可见 | 关节量 `θ` | `Articulate(F, −θ, axis)`（刚体）/ 重折（非刚体） |
| `Insert(F_obj, F_tgt, d)` | 对准并插入深度 `d` | 轴对齐 | 插入 `d` | `Extract(F_obj, F_tgt)` |
| `Extract(F_obj, F_tgt)` | 拔出 | 已插入 | 分离 | `Insert` |
| `Place(F_obj, F_sup)` | 放到支撑/容器 | `held(F_obj)` | 物体在 `F_sup` | `Pick(F_obj)` |
| `Pick(F_obj)` | 从支撑/容器取起 | 物体可达 | `held(F_obj)` | `Place(F_obj, last_support)` |
| `Pivot(Δθ)` | 底座/腰部重对准 | 底座可动/可转 | 底座转 `Δθ` | `Pivot(−Δθ)` |
| `Wait()` | 保持/等待人松手/放回 | — | 状态不变 | `Wait()` |

### 2.2 32 任务 `human_*` → 算子 → 可恢复性（权威快照）

**A. 纯平移型（`R1`，对象中心帧即可吸收）**
T01 杯子向后/向右；T02 水果向前/向右；T03 娃娃向前/向右；T04 盘子向左/梨向右；T06 绿积木向右/红积木向前；T07 相框向上；T09 胶带向后/向右；T13 试管向右/左；T15 钳子向左/螺丝刀向右；T18 文具盒向上/书包向左；T20 纸杯向上/向右；T21 盘子向前/架子向左；T22 字母上/左；T23 球拍前/左；T28 黄色盒耳机向前/红盒耳机向右；T30 黄色钉子到中间/绿色钉子向下。
→ 算子 = `MoveHeld` 或 `MoveObject`；恢复 = 重定位物体帧 + 续做。

**B. 容器/目标物平移型（`R1`，需重定位“目标帧”）**
T08 抓到书后挪动架子；T11 抓取后动绿色盒子；T25 放第一个后挪底座；T26 把插口移开；T29 外壳盖移开；T05 移动道具手握网口。
→ 算子 = `MoveObject(receptacle)` 或 `Pivot/MoveBase`；恢复 = 重定位 `F_target`，必要时 `Pivot` 重对准。

**C. 反向铰链/螺纹/拉链/折叠型（`R0`，逆算子直接可做）**

T16 叠完毛巾翻开 → `Articulate(fold, −)` / 非刚体展开，恢复“重新折”；

T19 拉上拉链后拉开 → `Articulate(zip, +)`，恢复 `Articulate(zip, −)`。
→ 这些是 v2「重做」最该落成逆算子的地方。

**D. 拔出/放回/移除型（`R1/R2/R3`，要分级）**
T10 将插头拔起 → `Extract(plug, strip)`，恢复 `Insert`（`R1`）；
T24 可乐/薯片快到了放回传送带起点 → `ResetToStart = Extract + Place(start)`，恢复 `Pick + Place(bin)`（`R1/R2`）；
T27 叠第二个后拿下第二个 → `Remove(bowl2)`；若仍在桌面可达 → `R2` 重叠；若已拿走 → `R3` 止损；
T12 中途把锁拿走 → `Remove(lock)`；不可达 → `R3` 止损/等待，**不重做**；
T05 把网线另一头也插上 → `Insert` 新增约束；恢复 = 先 `Extract` 多余端或改抓取策略（`R1/R2`）。

**E. 无显式 `human_*` 的任务**
T31 `pencil_case`、T32 `syring_water`：当前快照只有位置/干扰物/背景三轴（未文本化），**不设撤回靶点**；恢复策略只保留通用 `R3` 止损与 `R1` 重定位。手册公开后复核。

> **读表结论**：30 个带 `human_*` 的任务里，约 2/3 是纯平移/容器平移（`R1`），约 6 个是反向铰链/拉链/折叠/螺纹（`R0`），少数是拔出/放回（`R1/R2`），真正不可逆的移除集中在 T12/T27（以及 T01/T03 的 unseen 缺件）。这与 v2「至少 11 个撤回型」不矛盾，但更精确：**恢复的主力是 `R0/R1`，不是「所有干扰都重做」。**

## 3. UIP-18 · OCAF（对象中心动作帧与底座重对准）

### 3.1 机制

- 对每个活跃物体/容器 `O` 维护帧 `T_WO`（可从首帧、本体位姿、学习到的相对位姿获得；**不要求米制深度**，只要求相对帧）。
- 动作在 `O` 系生成：`a_O = Ad_{T_WO}^{-1} a_W`。物体被平移/旋转时，`T_WO` 更新，`a_O` 不变。
- `ee` 模式下直接生成 `F` 系位姿；`joint` 模式下用 IK 把 `a_O` 映射到关节目标，并做限位/最小 jerk。
- **底座通道**：`action.pivot[7]` 是共享键。T11/T25/T26 的「动底座/动目标」可先 `Pivot(Δθ)` 把工作区转回可达范围，再重定位目标帧；这比盲目重抓更省步数。
- **非刚体**：毛巾/拉链布用折叠线/拉链头关键点作为“对象帧”，逆操作用“重新折/重新拉”，不用刚体逆变换。
- **失效保护**：若 `T_WO` 置信度低或物体被遮挡，进入 `occluded`，不触发逆算子；回云端或 `Wait`。

### 3.2 形式不变式

若扰动是刚体 `D_T`，且 `T_WO' = D_T T_WO`，则对任意 `a_O`：
`Ad_{T_WO'} a_O = D_T Ad_{T_WO} a_O`，
即“对象系动作在世界系里跟着物体一起被变换”。因此 `R1` 的恢复不需要重新学习“物体新位置下的动作”，只需要更新 `T_WO`。这把「位置泛化」从数据问题变成**坐标系问题**。

## 4. UIP-19 · EDS（云端规划 / 边缘执行的部署拆分）

### 4.1 分工

| 层 | 运行内容 | 延迟量级 | 是否学习 |
|---|---|---|---|
| 云端 VLA | 语义理解、算子段规划、歧义消解、长程步骤账本 | 高（完整前向） | 是（唯一 checkpoint） |
| 边缘执行器 | 算子编译、IK/限位/最小 jerk、块边界 5 态验证、逆算子合成、动作拼接 | 低（确定性 + 小头） | 否；恢复头与云端共享骨干/同权重蒸馏 |
| 评测端 | 执行恰好 `T_a` 步、回传边界观测 | — | — |

**关键点**：边缘不改变 `T_a`，也不做块内闭环；它做的是**块边界上不叫醒云端也能继续/撤销一个算子**。

### 4.2 延迟与可信度

- 云端每次边界都调用：`L_C = P + RTT + T_C + T_io`；
- 边缘续做/撤销：`L_E = P + RTT + T_E + T_io`；
- 边缘只在需要新算子/歧义时回云端，降低平均延迟与方差；
- 对 N 端口：边缘执行器无状态或每端口状态隔离；云端共享权重、请求批处理；每端口 `reset` 独立。
- **投机算子预计算**：在机器人执行当前块时，边缘按“最可能的下一状态”预编译候选算子块；到边界只做一致性检查与选择。若观测不符，回云端。这压平 `T_decision` 的方差，但不改变 `P`。

### 4.3 单模型合规

- 一个学习 checkpoint（云端 VLA）。
- 边缘算子库是确定性代码；恢复头若是学习式，必须与云端共享骨干或从云端蒸馏，且不引入外部 VLM。
- 所有 N 端口共享同一模型权重，仅状态隔离；不把“多端口”解释成“多模型”。

## 5. UIP-20 · DAF（扰动即动作的数据工厂）

### 5.1 机制

在 Gazebo/DRF 中不再“演一段干扰动画”，而是**按算子生成三元组**：
`(x_pre, D, x_post)`，其中 `D ∈ O*` 是平移/旋转/铰链/插入/移除/底座；
再让示范者执行 `Inv(D)`，得到 `(x_pre, D, Inv(D), x_rec)`。
- 训练 **算子识别头**：从边界观测变化预测 `D` 的类型/参数/可恢复性；
- 训练 **逆算子选择头**：在 `{R0,R1,R2,R3}` 上分类，并回归逆算子参数；
- 校准 **`occluded` 检测**：遮挡/出画/图像损坏的负样本；
- 覆盖 **时机/速度/幅度随机化**：干扰发生在块内任意时刻，验证 `T_a` 下的检出率。
- 与 v2 DRF 的区别：v2 生成“恢复演示”，但恢复动作是脚本化的连续轨迹；DAF 生成**算子级配对**，直接监督“识别+逆算子”，可跨任务共享。

### 5.2 数据规模与标签

- 每个任务按 §2.2 的算子类型生成 50–200 个 `(D, Inv(D))` 对；优先 T14/T16/T17/T19（`R0`）、T08/T11/T25/T26/T29（`R1`）、T10/T24/T27（`R1/R2`）、T12（`R3`）。
- 标签只需算子类型/参数/可恢复性，不需要逐帧计分标注；步骤分账本用 §0 权威表。
- 真机锚点：每个算子族至少 5–10 次真机验证，校准仿真与真机的逆算子成功率。

## 6. 关键算法：动作空间恢复（完整伪代码）

```python
# ---------- 动作空间与算子 ----------
@dataclass
class Op:
    kind: str                 # MoveHeld/RotateHeld/Articulate/Insert/Extract/Place/Pick/Pivot/Wait/Remove
    obj: str | None = None
    target: str | None = None
    param: tuple = ()
    def inverted(self):       # 仅对可逆算子
        if self.kind == "MoveHeld":   return replace(self, param=(-self.param[0],))
        if self.kind == "RotateHeld": return replace(self, param=(inv_rot(self.param[0]),))
        if self.kind == "Articulate": return replace(self, param=(-self.param[0], self.param[1]))
        if self.kind == "Pivot":      return replace(self, param=(-self.param[0],))
        if self.kind == "Insert":     return Op("Extract", self.obj, self.target)
        if self.kind == "Place":      return Op("Pick", self.obj)
        raise NoInverse(self.kind)

# ---------- 边界验证（5 态） ----------
def verify(obs, g, hist, vis_conf):
    phi = predicate(obs, g)                     # 0/1/None
    if phi is None or vis_conf < TH_VIS:
        return "occluded"
    if phi == 1:
        return "done"
    if hist[g].ever_done and not obs.occluded(g):
        return "regressed"
    if hist[g].attempts >= N_FAIL:
        return "fail"
    return "ongoing"

# ---------- 逆算子恢复 ----------
def recover(D, obs, budget):
    rc = recoverability(D, obs)                 # R0/R1/R2/R3
    if rc == "R3":
        return [Op("Wait")], "stop_loss"
    if rc == "R0":
        return [D.inverted()], "inverse"
    if rc == "R1":
        F = relocalize(D.obj or D.target, obs)  # 更新对象中心帧
        return [D.inverted().with_frame(F)], "relocalize+inverse"
    if rc == "R2":
        return [Op("Reach", D.obj), Op("Grasp", D.obj), D.inverted()], "regrasp+inverse"

# ---------- 编译成恰好 T_a 步 ----------
def compile_TO(plan, obs, T_a, prev_chunk):
    acts = []
    for op in plan:
        traj = traj_of(op, obs)                 # (tau, |A|)
        acts.extend(traj)
        if len(acts) >= T_a: break
    acts = acts[:T_a]
    while len(acts) < T_a:
        acts.append(hold(obs))                  # 保持/续做
    acts = jerk_blend(prev_chunk[-1], acts, b=3)
    acts = clip_bounds(acts, obs)
    return pack(acts, T_a, token=TOKEN)         # 每个 key 形状 (T_a, …)
```

**接口红线检查**（每次返回前）：
- `control_space` 是 `joint` 还是 `ee`，只返回对应双臂键 + 共享 `gripper`/`pivot`；
- 每个动作数组形状恰好 `(T_a, …)`；
- `meta.token` 与握手 token 一致；
- 无 NaN/Inf，动作在限位内；
- 动作差分有界（避免统计异常）。

|---|---|---|---|
| E301 | 盲目重做 vs 逆算子恢复 vs 云端重新规划 | 步骤分 / 成功率 / 恢复时延 | 逆算子 ≥ 重做 +15% 步骤分，且延迟更低 |

| E308 | 端到端 v3（16+17+18+19）vs v2 | 成功率 + 步骤分综合 | 相对 v2 显著提升；分轴报告 |

**必做的消融/证伪**：
- 去掉 `occluded` 态 → 误重做率应上升（证明该态必要）；
- 去掉逆算子、只做“重做当前技能” → 在 T14/T16/T17/T19 上应明显变差；
- 去掉 OCAF、用世界系动作 → 在 T08/T11/T25/T26 的平移干扰上应明显变差；
- 边缘路径只在“无新算子”时生效；若强制所有边界走边缘，遇到未见物体应退化（证明云端回退必要）。

## 9. 合规与风险

- **单模型**：一个学习 checkpoint；边缘算子库确定性；恢复头共享骨干/同权重蒸馏；不引入外部 VLM。
- **接口**：`T_a` 固定、每个数组恰好 `(T_a,…)`、`token` 每次携带、N 端口状态隔离、并发不互相阻塞。
- **无深度/无力控**：OCAF 用相对帧/学习特征，不做米制深度重建；插入/拧动靠位置伺服与视觉，不假设力控。
- **不可逆移除**：T12/T27 等明确归入 `R3`，止损/等待；盲目重做会浪费时间并破坏动作统计。
- **仿真过拟合**：DAF/GSO 只做结构/顺序校准；每个算子族必须有真机锚点；不得把 Gazebo 成功率当榜单结论。
- **手册缺口**：控制频率、episode 时限、评测轮次、位置/干扰物/背景三轴的细节仍未取到；`T_a` 与预算需用探针实测。

## 10. 本轮最大风险 & 押注

**一句话**：整套方案的前提是「人为干扰大多可被机器人自己的动作语法逆运算、且能在块边界用一个轻执行器完成」；若真实干扰以不可逆移除、非刚体形变或遮挡为主，或 `T_a`/控制频率使边界反应太慢，逆算子就会退化成昂贵空转——必须用可恢复性分级、`occluded` 态、逆算子预算和真机锚点把“能逆/不能逆”分开，宁可止损也不要盲目重做。

**→ 本轮最值得押注：UIP-16 EAR-Gov × UIP-17 AOG × UIP-18 OCAF 组成的「块边界逆算子恢复」**——它把 v2 里最含糊的 `redo` 落成动作空间里可执行、可预算、可审计的恢复动作，直接对准 30/32 任务都写明的 `human_*` 干扰轴，且完全落在选手 API 权限与单模型合规之内。**第二优先是 UIP-19 EDS**：它不改变 `T_a`，只把每次边界决策从“叫醒完整 VLA”降为“边缘算子执行”，用延迟稳定性换取可信度。
