# 第 1 轮（UniBot 线 · 本轮灵感：「云边协同」×「对比实验」）

> **承接声明**：接续既有 UniBot 基线（上一版以「抓取 × 技能学习 × 地形适应」组织，已确立四条硬结论：①计分近共线 ⇒ 只优化终态成功；②任务间专长准正交 ⇒ 通用 = 技能向量；③断点在最后对齐/插入/释放；④"做得快"无红利）。本轮**不推倒**，而是把上一版隐含的**部署拓扑**显式化，并把"如何证明它有效"升级为**资源对齐的因果对比**。编号切换：本轮启用定义 C1–C12、引理 CL1–CL8、实验 E701–E718；上一版 U1–U12 / L1–L7 / IP-01–IP-08 / E601–E618 作为**已封存基线**按需引用。榜单数字仍属 teaser/占位表（检索 2026-11-17），仅作结构参考。

## 0. 一句话路线

上一版把系统写成"三层栈"，但**默认全部跑在一台机器上**；本轮承认 UniBot 赛制本身就是一个**分布式系统**（选手远程部署服务 × N 台真机 × 官方采集延迟/抖动），据此提出 **SkyBridge**：把"深思"放在云、把"反射与安全"放在边，用**推测执行（speculative execution）**把响应延迟与云延迟解耦；同时用一套**算力/延迟对齐的析因对比实验**，把"云边架构的增益"与"单纯更多算力"分离开来。

## 1. 直觉（两灵感的第一性原理）

**灵感 1「云边协同」→ 接口本身就是一条广域链路，延迟不是噪声而是设计变量。**

第一性原理：UniBot 的 `get_action(obs)` 是同步调用，官方采集 per-step 延迟；而选手服务通常不在机器人旁。设云端推理 35–70 ms、公网 RTT 20–80 ms、N 台机器人共享后端再叠加 10–30 ms 排队，则**阻塞式云调用**的 p99 很容易越过上一版设定的 ~105 ms 预算。结论：不能"把大模型放云上然后同步等结果"。正解是把**动作块（action chunk）当成分组交换的单位**：云异步产出带时间戳与有效期的块，边用**本地缓冲 + 反射**立即应答，云块到达后经安全盾校验再缝入未来步。这样 **响应延迟由边决定、语义质量由云决定**，二者解耦。边还承担三件云做不了的事：安全投影（关节/速度/碰撞/夹爪合法）、事件反射（滑移/卡滞/接触/超时）、按端口的状态隔离。

第一性原理的推论：**推测执行把"云延迟"从响应路径上移走，只把"云质量"留在决策路径上**；代价是动作可能"陈旧"（stale），因此必须用**时滞感知的本地权威**（越旧越多用边反馈）来补偿。

**灵感 2「对比实验」→ 云边最容易被"更多算力"冒充，必须做资源对齐的析因。**

第一性原理：任何"云边 vs 全云"的对比，若云的模型更大、GPU 更多，赢的可能是**容量**而非**架构**；若云边把 p99 压低了，赢的可能是**延迟**而非**分工**。因此"云边协同有效"是一个**因果命题**，需要控制混淆：至少对齐 (a) 总 FLOPs、(b) p99 响应延迟、(c) 观测/动作带宽、(d) 同一 checkpoint 的共享模块。做法是 **2×2×2 析因 + 配对设计 + 预注册 + 多重比较校正**，并把"匹配算力后增益是否消失"设为主判据——这是一个**可被证伪的强命题**，而不是"我们搭了个系统、它跑起来了"。

第一性原理的推论：**对照实验的价值不在于"证明我对"，而在于设计一个能让"我错"显形的实验**。因此本轮把"负结果"（匹配后增益归零）写成合法的、可发表的结论，并预置降级路径。

**合成**：云边协同给出**结构**（云深思 / 边反射 / 推测解耦 / 安全盾 / 端口隔离）；对比实验给出**证据纪律**（资源对齐、析因、配对、预注册、多重校正）。前者是待检验的假设，后者是让假设可被杀死的方法。⇒ **SkyBridge = Cloud-Edge Speculative Deliberation + Resource-Matched Causal Comparison。**

## 2. 严谨定义（预览；完整符号与公式见产物区 §3）

- **分区** `P: M→{cloud,edge}`：模块到执行位置的映射，附延迟/算力/带宽代价模型。
- **意图块** `κ=(g, z_phase, a^C_{1:T_a}, t_gen, h, conf)`：云端产出的子目标 + 相位 + 动作块 + 生成时刻 + 有效期 + 置信度。
- **时滞** `Δ_t = t − t_gen`：块被使用时的年龄；边按 `Δ` 调整"本地权威"。
- **推测缓冲** `B`：待提交块队列；提交策略 `Commit(B,o)`。
- **安全盾** `S(a,o)=Proj_{A_feas(o)}(a)`：把动作投影到可行集（关节限位/速度/碰撞/夹爪合法）。
- **边反射** `ρ(e,o)`：事件 `e∈{slip,stall,contact,timeout}` 触发的高频覆盖动作。
- **资源向量** `r=(FLOPs, p99, BW, mem)`；**资源对齐**：两系统 `‖r−r'‖≤ε`。
- **因果归因**：只有当对比资源对齐且随机化时，成功率差才可归因于架构。
- **可信度** `T`：由延迟分布与动作规律性导出的审计分数。

## 3. 研究问题（可证伪）

- **Q1（解耦是否成立）**：推测执行能否在云端 p99 超预算时仍把边侧 p99 压到预算内，且成功率不低于阻塞式全云？给出"时滞—成功率"曲线及其拐点。
- **Q2（架构 vs 容量）**：在**总 FLOPs 与 p99 对齐**后，云边分工相对全云/全边是否仍有增益？若增益消失，则承认"只是更多算力"。
- **Q3（安全盾的净效应）**：安全盾的假覆盖（把本来正确的可行动作改掉）率有多高？它防住的不可行动作与误伤的可行动作，净成功率是正还是负？
- **Q4（反射的边界）**：哪些事件（滑移/卡滞/接触/超时）值得边反射介入？介入的收益/代价比与最大次数是多少？
- **Q5（分区的最优性）**：在延迟敏感相位（grasp/align/insert）与容量敏感相位（语义/长程）之间，分区是否存在可计算的阈值？把云输出从"原始动作"改为"意图/子目标"是否提升鲁棒性？
- **Q6（对比实验的效力）**：在真机稀缺下，怎样的配对/析因/预注册设计能在给定样本量下检出可解释的效应，且不被多重比较与任务异质性欺骗？

## 4. 设计原则（在 P1–P6 上增补）

- **P7 延迟是设计变量**：任何模块必须标注其延迟敏感度；同步阻塞云调用默认禁止，除非实测 p99 达标。
- **P8 边可独立安全**：边必须在云完全失联时仍能安全执行/停车/重抓（退化链不依赖云）。
- **P9 资源对齐才可归因**：凡声称"架构有效"，必须给出匹配算力/延迟的对照，否则只算工程收益。
- **P10 预注册与配对**：确证性真机实验先冻结假设、指标、停止规则与分析计划；按任务×场景×种子配对，随机化端口/顺序。
- **P11 可信度是一等约束**：推测与反射会改变动作统计，必须整形并自证，不能以"不可审计的抖动"换成功率。

## 6. 与基线的差异（为什么是现在）

- 上一版 IP-03 的"chunk 缝合"是**单机**的连续性修补；本轮把它升级为**跨网络的推测缓冲**（时滞感知、可拒绝、可审计）。
- 上一版 IP-08 的"可审计"是**单机埋点**；本轮面对的是**分布式不确定性**（网络抖动 + 并发 + 推测切换），审计对象变成"可信度在资源受限下是否仍达标"。
- 上一版最大风险是"抓握伪标签漂移"；本轮新增一个更硬的风险：**资源对齐后增益归零**。这正是"对比实验"灵感要提前杀死的假设。
- 与榜单模型相比：它们大多是"单机单体、同步出块"；云边推测是**赛制红利**（自行部署、远程接入、可反复提交）的直接兑现——但要先过合规与可信度两道闸。

## 7. 本轮最大风险

一句话：**一旦把总算力与 p99 延迟对齐，云边协同的增益可能被证明只是"更多算力"的伪装；而分布式带来的时滞抖动与推测切换，又恰好撞上官方"延迟与动作规律性"的可信度审核——即既可能被证伪，也可能被判不可信。**

## 0. 本轮结论摘要

**一句话**：把 UniBot 的"远程部署 + N 真机 + 延迟审计"当作分布式系统来设计——**云出意图块、边做推测与安全反射**——并用**资源对齐的析因对比**把"架构增益"从"算力增益"里剥出来。

**三条可执行判断（含算例）**：

| 判断 | 算例/依据 | 推出的设计 |
|---|---|---|
| 阻塞式云调用在 p99 上不可行 | 云推理 35–70 ms + RTT 20–80 ms + 并发排队 10–30 ms ⇒ 长尾 ≈ 105–180 ms，越过预算 | **推测缓冲**把响应延迟钉在边侧（SB-01） |
| 推测的收益是"时滞可容忍度" | chunk=8@30fps ≈ 267 ms；云每 ~150 ms 补一块即不空 | 边按 `Δ` 增大本地权威（CL1，SB-01/SB-03） |
| 主判据是"匹配后是否还赢" | 2×2×2 析因，对齐 FLOPs 与 p99 | 若匹配后增益 < 预注册阈值 ⇒ 判定"只是更多算力"并降级（SB-05，P9） |

**合规红线（沿用 P5/P6）**：对外仍是**单一 checkpoint、单一 API 服务**；云边是其**内部实现**，安全盾/反射为**规则化模块**（非第二个学习模型），不构成"多模型 ensemble"；提交前需向组委会书面确认"分布式部署"合规。

## 2. 创新点详述

### SB-01 · Speculative Chunk Buffer 推测缓冲（P0）

- **动机**：`get_action` 同步、官方测 per-step 延迟，而云调用长尾超预算（§0 算例）。若阻塞等云，延迟与成功率二选一。
- **与现有方案的差异**：常规做法是"服务端算完整块再返回"（单体同步）。我们把动作块视为**可推测的分组交换单元**：边维护待提交队列，立即返回队首动作，同时异步向云请求新块；新块到达后经安全盾校验再入队。响应路径与云路径解耦。
- **技术可行性**：高。仅需官方 client 语义（chunk 如何执行/是否插值）实测后实现；边逻辑为 O(1)。
- **落地步骤**：①用 `run_server.py` + `run_client.py` 复刻评测闭环，测真实延迟与 chunk 语义；②实现双缓冲（committed / pending）；③提交规则：`conf ≥ τ_c ∧ Δ ≤ h ∧ shield-valid`；④时滞感知权威 `w(Δ)=clamp(1−Δ/h,0,1)`，越旧越依赖边反馈；⑤断网/超时退化为边外推 + 减速。
- **风险**：①评测端自带插值/平滑 ⇒ 推测切换被叠加抖动（以真机 A/B 定是否启用，默认可关）；②陈旧动作导致漂移（用 `w(Δ)` 与安全盾约束）；③动作统计变得不规则 ⇒ 撞可信度审计（SB-06 对冲）。

### SB-02 · Safety Shield 安全投影（P0）

- **动机**：云块可能含不可行动作（超限位/超速度/自碰/夹爪越界），边是最后一道物理闸门。
- **差异**：多数提交信任云输出直接下发；我们在边做**可行集投影**并**审计假覆盖**。
- **可行性**：高。关节限位/速度/加速度/夹爪范围可直接从观测与 metadata 得到；碰撞用点云/深度近似（若接口提供）。
- **落地步骤**：①定义 `A_feas(o)`（硬约束：限位、速度、夹爪范围；软约束：桌沿距离）；②投影 `S(a)=argmin_{a'∈A_feas}‖a−a'‖`；③只对**硬约束**投影，语义修正一律不做（避免假覆盖）；④记录每次覆盖（原因、幅度、是否改变了成功轨迹）。
- **风险**：假覆盖（把正确动作改掉）直接降成功率 ⇒ 仅在硬约束触发；阈值由数据分布定；E705 专项测净效应。

### SB-03 · Edge Reflex 事件反射（P0）

- **动机**：滑移/卡滞/接触/超时是**高频、短窗口**事件，等云往返已错过恢复窗口；且上一版断点在"最后对齐/插入/释放"。
- **差异**：把"抓握确认 + 重抓"从云端下沉到边，做成**事件驱动反射**（规则/轻量分类器），与云端语义解耦。
- **落地步骤**：①事件定义（滑移=EE 位移与物体随动不一致；卡滞=指令-实际速度差持续；接触=力/电流突增；超时=块耗尽）；②反射动作库（松-重抓 / 回退 2 cm 再对齐 / 减速 / 停车）；③介入准则：仅高精度事件触发，`≤3` 次上限；④与 SB-01 的权威权重联动。
- **风险**：误触发打断正确轨迹 ⇒ 高阈值 + 上限 + 可关闭；反射本身改变动作规律性 ⇒ 整形并审计。

### SB-04 · Intent-Level Cloud 意图级云输出（P1）

- **动机**：原始关节动作对时滞最敏感；若云只出"子目标 + 相位 + 粗动作"，边可在本地闭环精修，时滞鲁棒性更高。
- **差异**：把云输出从 `a^C` 升维为 `(g, z_phase, a^C, conf)`，边用局部反馈补齐最后一公里。
- **落地步骤**：①云头增加子目标/相位输出；②边用视觉伺服/EE 位姿做局部对齐；③A/B：意图级 vs 动作级在注入时滞下的成功率。
- **风险**：意图到动作的落地依赖边控制器质量；若边控制器弱，反而不如原始动作。

### SB-05 · Resource-Matched Comparative Protocol（P0）

- **动机**：云边增益可能只是"更多算力/更低延迟"的伪装。没有资源对齐，结论不可归因。
- **差异**：多数机器人论文只比"我的系统 vs 基线系统"；我们做**资源对齐的 2×2×2 析因 + 配对 + 预注册 + 多重校正**，并把"匹配后增益归零"设为合法的负结果。
- **落地步骤**：见 §7（完整设计）。核心：因子 = {计算位置, 总算力, 网络条件}；对照 = 全云/全边/云边/延迟匹配云/容量匹配边；配对 = 任务×场景×种子；统计 = McNemar + bootstrap + Holm。
- **风险**：真机样本量不足以检出小效应 ⇒ 分层（代理覆盖小效应、真机确证大效应）；任务异质性 ⇒ 层级模型 + 最差任务报告。

### SB-06 · Trustworthy Speculation Audit（P1）

- **动机**：官方明示会采集 per-step 延迟及其波动、动作统计规律性来评估可信度；推测会引入切换方差。
- **差异**：把"可信度"变成可导出的审计产物（延迟 p50/p99/jitter、jerk、动作熵、切换率），而非事后祈祷。
- **落地步骤**：①埋点；②动作整形（切换处速度连续、限幅）；③导出报告；④E710 验证。
- **风险**：过度整形压低成功率 ⇒ 只整形残差，不改均值；保留策略固有随机性，不做"拟人化"噪声。

### SB-07 · Port-Isolated Edge Sessions（P0）

- **动机**：N 台真机随机顺序、连续端口、每端口独立全流程；共享后端必须并发安全 + 状态隔离。
- **落地步骤**：①每端口一份 Session（缓冲/反射计数/审计）；②`reset()` 彻底清空；③N×8 h 压测 + 串扰检测；④端口数自检（8765…8765+N−1）。
- **风险**：跨端口状态泄漏或 token 错配 ⇒ 自动化体检脚本。

## 3. 符号与定义（C1–C12）

| 符号 | 含义 |
|---|---|
| `π_C` | 云端深思策略（高容量/高延迟，异步产出意图块） |
| `π_E` | 边端反射策略（低延迟，安全/事件驱动） |
| `P` | 分区映射 `M→{cloud,edge}` |
| `κ` | 意图块 `(g, z_phase, a^C_{1:T_a}, t_gen, h, conf)` |
| `Δ_t` | 时滞 `= t − t_gen` |
| `B` | 推测缓冲（committed / pending 双队列） |
| `S` | 安全盾 `Proj_{A_feas(o)}` |
| `ρ` | 边反射算子 `(e,o) → a` |
| `r` | 资源向量 `(FLOPs, p99, BW, mem)` |
| `ε` | 资源对齐容差 |
| `T` | 可信度分数 |
| `Γ` | 对比实验的析因/因果设计 |

**定义 C1（SkyBridge 策略）** `π_SB(o_t) = Commit(B, o_t)`，其中 `B` 由异步的 `π_C` 与同步的 `ρ/S` 共同更新；对外仍是单 `get_action`。
**定义 C2（意图块）** `κ=(g,z_phase,a^C_{1:T_a},t_gen,h,conf)`，`h` 为有效期，`conf` 为块级置信度。
**定义 C3（时滞）** `Δ_t = t − t_gen`；块仅在 `Δ_t ≤ h` 时可用。
**定义 C4（提交策略）** `Commit(B,o)= a_1`，其中 `B` 的队首块满足 `conf≥τ_c ∧ Δ≤h ∧ S(a_1,o)=a_1`；否则回退 `ρ` 或外推，并标记 `degraded`。
**定义 C5（安全盾）** `S(a,o)=argmin_{a'∈A_feas(o)}‖a−a'‖`；`A_feas` 只含硬约束（关节限位/速度/加速度/夹爪范围）。
**定义 C6（边反射）** `ρ(e,o)`：`e∈{slip,stall,contact,timeout}`，输出覆盖动作或 `None`；触发需 `score(e)>τ_e` 且 `n_retry<3`。
**定义 C7（有效延迟）** `L_eff(o)=t_resp−t_recv`，即 `get_action` 墙钟时间；推测下 `L_eff` 由边决定。
**定义 C8（资源向量与对齐）** `r=(FLOPs,p99,BW,mem)`；`r≈r'` 当 `∀i, |r_i−r'_i|/r_i ≤ ε_i`。
**定义 C9（因果估计量）** `ATE(arch) = E[Y | do(arch=split), r] − E[Y | do(arch=cloud), r]`，仅在资源对齐 `r` 与随机化下可识别。
**定义 C10（分区目标）** `P* = argmax_P E[Y | P] − λ·E[L_eff | P]`，`λ` 为延迟惩罚权重。
**定义 C11（可信度）** `T = f(p50, p99, jitter, jerk, entropy, switch_rate)`，对各量单调（延迟/抖动/切换率越低越好）。
**定义 C12（对比协议）** `Γ=(H, factors, contrasts, pairing, α, power, stopping)`，见 §7。

```python
# ===== SB-01/02/03/07：边端守护进程（单一 API，内部云边协同）=====
class EdgeDaemon:
    def __init__(self, cloud_client, budget_ms=105, tau_c=0.6):
        self.cloud = cloud_client
        self.sessions = {}          # port -> Session（状态隔离）
        self.budget_ms = budget_ms
        self.tau_c = tau_c

    def reset(self, port):
        self.sessions.setdefault(port, Session()).reset()

    def get_action(self, obs, port):
        s = self.sessions[port]
        t0 = time.perf_counter()

        # 1) 异步请求云块（不阻塞响应路径）
        self.cloud.request_async(obs, port, ctx=s.ctx)

        # 2) 尝试提交已就绪的云块（时滞感知 + 安全盾）
        a = None
        for kappa in s.pending_ready():
            if kappa.conf >= self.tau_c and kappa.age() <= kappa.h:
                cand = kappa.a[0]
                if np.allclose(SafetyShield.project(cand, obs), cand):
                    a = cand
                    s.commit(kappa)          # 移到 committed
                    break

        # 3) 边反射（滑移/卡滞/接触/超时）优先于陈旧云块
        e = detect_event(obs, s.last_action)
        if e and s.n_retry < 3:
            a = Reflex(e, obs) or a
            s.n_retry += 1

        # 4) 兜底：外推 / 减速 / 停车（云失联也可安全）
        if a is None:
            a = s.extrapolate_or_stop(obs)
            s.audit.mark_degraded(port)

        # 5) 整形 + 审计（延迟/抖动/jerk/切换率）
        a = Shape.smooth(a, s.last_action)
        s.audit.log(port, a, (time.perf_counter() - t0) * 1000)
        s.last_action = a
        return pack(a, obs)
```

# ===== SB-01：推测缓冲提交规则（C4）=====
def commit_ready(session, obs, tau_c):
    for kappa in session.pending:
        stale = kappa.age() > kappa.h
        invalid = not SafetyShield.is_feasible(kappa.a[0], obs)
        if stale or invalid or kappa.conf < tau_c:
            session.audit.reject(kappa)
            continue
        return kappa.a[0]
    return None

## 5. 推导（引理 CL1–CL8）

**引理 CL1（时滞—跟踪误差界）** 设闭环局部 Lipschitz 常数 `L`，云块基于 `t−Δ` 时刻状态生成。则开环执行误差满足 `e(Δ) ≤ (e^{LΔ}−1)·‖v‖/L + e^{LΔ}·e(0)`，对 `Δ` 单调递增。边反馈以增益 `k` 将有效 `L` 降为 `L−k`，故同一 `Δ` 下误差更小；时滞感知权重 `w(Δ)=1−Δ/h` 即是对该界的线性近似补偿。∎

**引理 CL2（推测非回归）** 若云块总被确认（`p_reject=0`）且安全盾只投影不可行动作（假覆盖 `=0`），则推测执行与阻塞执行产生**相同**的动作序列，成功率相同。一般情形下，期望成功变化 `≤ −p_reject·ℓ_r + gain_latency·ℓ_l`；仅当 `gain_latency·ℓ_l > p_reject·ℓ_r` 时推测净收益为正。∎

**引理 CL3（安全盾权衡）** 记 `p_inf=P(动作不可行)`、`r_catch=P(盾拦截|不可行)`、`f_false=P(盾覆盖|可行)`。净成功率变化 `≈ r_catch·p_inf·g_saved − f_false·(1−p_inf)·ℓ_wrong`。当 `f_false ≤ r_catch·p_inf·g_saved / ((1−p_inf)·ℓ_wrong)` 时为正。故只对**高 `p_inf`、低 `f_false`** 的硬约束启用投影。∎

**引理 CL4（资源对齐可识别性）** 观测差可分解 `ΔY = ΔY_arch + ΔY_capacity + ΔY_latency + ΔY_interaction`。当 `r≈r'`（容量与延迟期望对齐）且随机化成立时，后三项期望为零 ⇒ `ΔY` 识别 `ΔY_arch`。不匹配时 `ΔY_capacity` 与 `ΔY_arch` 混淆，结论不可归因。∎

**引理 CL5（推测下的可信度）** 推测降低 p99 但抬高动作切换方差 `σ_switch`。`T` 对 `p99` 与 `σ_switch` 单调递减，故存在推测率 `λ*` 使 `T` 在成功率约束下最大；无约束地追求低延迟会损害 `T`。∎

**引理 CL6（分区阈值）** 在可加模型下，模块 `m` 迁云当且仅当 `c_m·Δsucc > λ·(ℓ_cloud−ℓ_edge)`，`c_m` 为容量收益、`λ` 为延迟惩罚。抓握/对齐等延迟敏感模块 `λ` 大 ⇒ 留边；语义/长程模块 `λ` 小 ⇒ 上云。∎

**引理 CL7（对比功效）** 二值成功的配对检验（McNemar）所需对数
`n ≈ (z_{1−α/2}+z_{1−β})²·(p01+p10)/(p10−p01)²`。
取 `α=0.05, power=0.8`（`z≈1.96,0.84`），不一致率 `p01+p10=0.20` 时：`δ=0.10→n≈157`，`δ=0.08→n≈245`，`δ=0.05→n≈627`。故真机确证以大效应（`δ≥8–10pp`）为主，小效应交给代理评测。∎

**引理 CL8（任务异质性与全局均值的陷阱）** 基线测得跨任务 Kendall `τ≈0.064`（准正交）。此时全局均值胜出可与**多个任务的回退**并存。故必须报告**每任务效应 + 最差任务**，并用层级模型（任务随机效应）估计总体，禁止只看总均值。∎

## 7. 对比实验设计（本轮核心，E701–E718）

### 7.1 假设与主判据（预注册）

- **H1（架构 vs 容量，主判据）**：在总 FLOPs 与 p99 对齐后，`split` 相对 `all-cloud` 的成功率差 `ΔY_arch > δ0`（`δ0=3pp` 为最小有意义效应）。
- **H2（推测 vs 阻塞）**：`split+spec` 相对 `split+blocking` 的边侧 p99 更低且成功率不降。
- **H3（安全盾净效应）**：`shield on` 相对 `off` 的成功率差为正（CL3 条件成立）。
- **H4（反射净效应）**：`reflex on` 相对 `off` 在插入/抓取类任务上为正。
- **H5（意图级 vs 动作级）**：注入大时滞时 `intent-level` 优于 `action-level`。
- **H6（分区消融）**：逐模块迁移的边际贡献可分辨。
- **主判据的可证伪性**：若 `H1` 不成立（`ΔY_arch ≤ 0`），则**撤回架构主张**，SkyBridge 降级为纯延迟工程（SB-01/02/03），并在报告中明确"增益来自资源而非架构"。

### 7.2 因子与水平（2×2×2 主析因 + 扩展）

| 因子 | 水平 | 目的 |
|---|---|---|
| A 计算位置 | `all-cloud` / `split` | 架构主效应 |
| B 总算力 | `low` / `high`（对齐 vs 不对齐） | 容量混淆检验 |
| C 网络条件 | `ideal` / `realistic`（注入 RTT/抖动/丢包） | 鲁棒性 |

扩展（非全析因，按需）：
- D 延迟预算 `tight/loose`；
- E 云输出 `action-level/intent-level`；
- F 推测 `on/off`；G 安全盾 `on/off`；H 反射 `on/off`。

### 7.3 对照与"资源对齐"的具体实现

| 臂 | 定义 | 对齐方式 |
|---|---|---|
| `all-cloud` | 云同步出原始动作块 | 云端模型缩放至与 split 的**总 FLOPs** 相同 |
| `all-edge` | 边本地小模型出块 | 边模型放大至同 FLOPs（模拟"把算力放边上"） |
| `split` | 云深思 + 边推测/盾/反射 | 共享同一 checkpoint 的共享模块 |
| `split-throttle` | split 但云延迟被节流到 `all-cloud` 的 p99 | 延迟对齐（检验"是否只是更快"） |
| `split-matched` | split 且总算力 = `all-cloud` | 容量对齐（主对照） |
| `split-noSpec` | split 但阻塞等云 | 隔离推测贡献 |

**对齐容差** `ε`：FLOPs `±5%`；p99 `±10%`；带宽 `±10%`；同一 `image_resize`、同一 `obs_delta_indices`、同一 `action_chunk_size`（除因子要求外）。

### 7.4 配对、随机化、盲法

- **配对**：同一 `(task, scene, seed)` 下多臂配对，消除任务难度与场景差异（基线任务内标准差均值 5.60，配对可大幅降方差）。
- **随机化**：每配对单元内臂顺序随机并**平衡**（拉丁方/轮转）；端口与机器人随机分配；网络条件按种子轮转。
- **盲法**：成功判定用固定规则/自动检查；人工评分者对臂盲。
- **停止规则**：固定样本量，不做可选停止；若用序贯，采用 alpha-spending。

### 7.5 指标

- **主指标**：终态成功率（二值）；步骤分（连续）。
- **机制指标**：边侧 p99 延迟、`Δ` 分布、盾拦截率/假覆盖率、反射触发率与恢复率、推测拒绝率、动作 jerk/熵/切换率。
- **异质性指标**：每任务效应、最差任务效应、跨任务 Kendall `τ` 的变化。
- **成本指标**：GPU 成本 / 每百分点成功率。

### 7.6 统计与功效

- 二值：配对 McNemar；效应 = 风险差 + Newcombe CI。
- 连续：配对 bootstrap（10k，BCa）。
- 任务异质：层级 logistic（任务随机效应），报告总体与最差任务。
- 多重比较：确证性对比用 Holm–Bonferroni（FWER=0.05）；探索性对比单列并标注。
- 功效（CL7）：真机确证目标 `δ≥8pp`、`n≈120–250` 配对 episode/对比；小效应（`δ<5pp`）只在代理评测上检验。

### 7.7 阶段化执行（代理 → 真机）

1. **S1 代理**：用官方 32 数据集做 OOD 切分 + 注入网络时滞，跑全析因，筛出大效应与失败模式。
2. **S2 真机确证**：只跑预注册的少数对比（H1–H5），配对 + 盲法。
3. **S3 校准**：估计代理↔真机相关性（Spearman `|r|≥0.5` 才允许用代理指标指导微调，否则触发剪枝）。
4. **S4 负结果归档**：若 H1 不成立，完整报告并降级。
