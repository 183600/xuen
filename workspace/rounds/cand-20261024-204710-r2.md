# 第 2 轮（承接第 7 轮状态）· T-SLAM：任务态 SLAM、步骤字典序、相位模块化

> 检索/复核日期：2026-10-24（UTC）。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「SLAM」「步骤分」「模块化设计」。我先纠正上一轮的两个偏差，再把三个词合成一个判断：**UniBot 的瓶颈不是动作生成，而是任务态估计（task-state estimation）——模型不知道“我现在在第几步、任务相关物体在哪、刚才的人为干扰改了什么”。SLAM 的正确降维不是机器人定位/稠密建图，而是“对象级、步骤索引、可验证、可重定位的任务态地图”；步骤分的正确用法不是主目标，而是语义骨架、字典序 tie-break 和瓶颈诊断；模块化的正确形态不是多模型堆叠，而是单 checkpoint 内的相位/能力路由。三者不是三个补丁，而是一个闭环：地图 → 步骤信念 → 相位专家 → 动作 → 地图更新 → 验证/重定位。**

> 说明：本文用 [S#] 标注来源，完整 URL/用途见产物区 §14；占位榜单数字只作弱先验，不作排名依据。

## 0. 本轮先核实与纠偏：六个事实

### 0.1 排名是“成功率先行”的字典序，不是加权综合

参赛手册（[S1][S2]）明确：每个任务 10 次独立运行，5 类泛化各 2 次；**实时榜单按 32 个任务的总平均成功率排序，成功率相同才按总平均步骤分排序，仍相同则提交日期较早者靠前**。

这修正了第 7 轮的一个隐含假设：上一轮把“成功率与步骤分综合排序”理解成某种加权，进而把终局步骤的 39.8% 步骤分当成可直接换算的排名收益。正确的目标函数是：

```text
主目标 = 32 任务 × 10 次 = 320 trials 的全任务成功率
次目标 = 步骤分（只在成功率打平时使用）
```

三个直接后果：

1. **终局放置的“闸门”论点更强，不是更弱。** 32/32 任务的成功都以终局步骤为必要条件；终局失败直接抹掉整次 success。
2. **“终局占 39.8% 步骤分”不能直接换成排名收益。** 部分分只在 tie-break 时有用；为了多拿 10 分步骤分而牺牲 1pp 成功率，是错误交易。
3. **统计噪声必须进入决策。** 320 trials、p≈0.30 时总体 SE≈2.56pp；+3pp 只有 1.2 SE，+5pp 约 1.95 SE。2–3pp 的“提升”很可能只是噪声；调试通道即便按 10 trials 计，SE≈14–16pp（实际 trial 数未公开），不能用来证明 +10pp。

但步骤分仍然重要，只是角色变了：

- **语义骨架**：94 个官方评分步骤是任务分解、相位标签、谓词定义的现成来源；
- **tie-break**：成功率接近时，步骤分决定名次；
- **密集信号**：步骤完成率比二值 success 更早暴露瓶颈；
- **诊断**：步骤级成功率向量能直接指出“钱丢在哪一步”。

一句话：**成功率先行，步骤分服务成功；不要反过来。**

### 0.2 榜单仍是占位，“头部不到 30%”不是已核实事实

`leaderboard.html` 可以渲染出 8 个模型和 29.7%/39.0 等数字，但 `leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，8 个模型 × 32 任务 = 256 条 `task_metrics` 是脚本生成；`runs.html` 仍是 256/256 占位，详情页写明视频占位（[S8][S9][S10]）。

因此：

- **“头部不到 30%”只能当弱先验，不能当事实。** 真实榜单发布后必须重跑所有头部分析。
- 占位模型名称对应的公开技术报告是真实的，可以用来看“头部做法与瓶颈”，但不能用占位数字判断谁强谁弱。
- 本轮的论点不依赖“30%”这个数：它依赖官方评分结构、官方数据/接口、以及 2026 年相邻领域的证据。即使真实头部是 50%，任务态估计仍然是瓶颈之一。

### 0.3 32 任务共 94 个评分步骤，终局是 32/32 的闸门

我复核了 32 个 `tasks_v2/<slug>/info.json`（[S3][S4]）。关键聚合：

- 32 任务、满分 100、**94 个评分步骤**、合计 3200 分；
- 终局步骤合计 **1275 分（39.8%）**；
- **32/32 任务的终局步骤都是该任务的最高权重步骤**；
- 18 个任务所有步骤等权；25 个任务终局权重 ≥40；
- 步骤数分布：11 个任务 2 步、14 个 3 步、5 个 4 步、2 个 5 步；
- 难度 12 Easy / 12 Medium / 8 Hard。

这给出一个比“终局权重最大”更精确的结构：

```text
success = ∏_k z_k            # 所有步骤完成才是 1（AND）
step_score = Σ_k w_k z_k     # 部分分（SUM）
ranking = lexicographic(mean success, mean step_score)
```

**AND 与 SUM 的错位**是上一轮最大的方法论风险：一个策略可以拿到很高的步骤分，却在最后一步失败；反过来，一个策略可能只差一步就全成功，但步骤分并不高。优化目标必须以 success 为主，步骤分只能做辅助/诊断/tie-break。

### 0.4 数据与接口：有校准立体，但没有 depth

官方数据与接口（[S5][S6][S7]）：

- 32 个数据集、约 32k–33k episodes、169h；每任务约 970–1,530 条；30fps；四路 RGB（左右高位 + 左右腕部），480×640；**无 depth 图像**；
- 但高位是**校准过的立体对**：HangCup 的 `camera_params.head_stereo` 给出 `rectified=true`、基线约 **58.25mm**、焦距约 **282px**；按 0.25px 亚像素视差、0.5m 处深度误差约 **3.8mm**，1px 视差约 **15mm**；1m 处 1px 约 **60mm**。这足够做“桌面对象级 2.5D 地图”，不够做毫米级插入——后者交给腕部视觉伺服；
- 状态含双臂 7+7 关节、EE pose（base/torso 两套）、夹爪、lower_body 15；数据集还含 `state_d435`/`state_torso` 相机位姿，但**提交 API 不暴露**；
- 每条任务在 `meta/tasks.parquet` 里有 5 条英文复述（抽查 HangCup/StackBowls/ZipUp/PlugCharger 均为 5 条，需全量核对）；
- API 观测只有四路 RGB、双臂关节/EE、夹爪、lower_body、单字符串 language；`metadata` 控制 `control_space`（joint/ee 互斥）、`obs_delta_indices`、`image_resize`、`action_chunk_size`、`token`；`reset()` 每 episode 一次。

这确认了两件事：

1. **我们可以在选手侧做立体匹配、对象跟踪、位姿图优化，不需要额外传感器。** 立体是接口内允许的观测，计算是我们自己的推理代码。
2. **地图必须是“轻”的。** 没有 depth、没有全局位姿、180s 限时、6B 级 VLA，做稠密 3D/NeRF/3DGS 是错误方向；对象级 2.5D + 关系 + 步骤谓词才是可部署的。

### 0.5 人类干扰备注是公开的逐任务剧本

每个任务的 `info.json` 的 `generalization` 字段直接给出 `human_1_note`、`human_4_note`、`unseen_object_3`（[S4]）。例如：

- T27：human_1「把粉色碗向下移动」；human_4「叠了第二个之后拿下第二个」；
- T19：human_1「把包向左边移动」；human_4「拉上拉链之后拉开」；
- T24：human_1「可乐快到了然后放回传送带起点」；
- T10：human_4「将插头拔起」；T12：human_4「中途把锁拿走」。

编号含义（轴编号还是试次编号）官方未解释，**不能断言这就是评测脚本**；但内容本身是高质量的场景先验：多数是“对某对象做一次 1-DOF 平移”或“在某步完成后撤销它”。这正好是任务态 SLAM 的测试台：地图要能检测“东西被动了”、重新定位、回滚步骤、恢复执行。

### 0.6 2026 的证据链：记忆、相位模块、步骤级评测都已成熟到可集成

- **对象/空间记忆**：SOMA 用持久空间记忆解决 out-of-vision 操作，减少视角搜索、接近 one-shot 抓取（[S12]）；OCC4M 用对象中心 4D 记忆 + 持久 track + 容器/运动关系，在 350 episodes 上把端到端成功率从 57.7% 提到 88.9%，视角切换后 98% vs 近零（[S13]）；DREAM 用 pose-graph-aware 的时空语义体素记忆做动态环境重定位（[S14]）；场景图 IL 把动态场景图当显式记忆，改善长程/部分可观测（[S15]）；FOUND-IT++ 把单目 3D 场景图接进完整移动操作管线，支持变化检测、多次建图、抓取（[S16]）；PhysMem 用“验证后再应用”的测试时物理记忆，在砖块插入上 76% vs 直接检索 23%（[S17]）。
- **相位/模块化**：PAMAE 用 phase-aware MoE 替换 flow-matching action expert，多阶段任务成功率最高 +9.2%（[S18]）；HiMoE-VLA 用层级 MoE 处理异构动作空间/观测，CALVIN 3.98、LIBERO 98.0%（[S19]）；RouteRLT 用“通才默认 + 精度阶段专家接管”，物理 connector 任务 65.7% vs 基线 8.6%（[S20]）；CORAL 用每任务 LoRA expert 解决多任务干扰，但需要 task routing，正好反证“按任务分专家”不适合 OOD 通才赛道（[S21]）；Emergent MoE 发现专家会自发对应可复用的低层行为（[S22]）。
- **步骤级评测**：StepEval 主张报告 per-subgoal success vector，而不是单一 success（[S23]）；Beyond Binary Success 用 SAVI 做小样本、序贯、统计严谨的策略比较，最多减少 70% 评测量（[S24]）；ManipArena 在真实机器人上做 subtask-level partial credit（[S25]）；“What Are We Actually Benchmarking” 警告 shortcut、统计不显著、creeping overfitting、数据源依赖（[S26]）。

这些证据大多来自相邻 setting（移动操作/仿真/非人形），不能直接外推；但它们共同支持一个假设：**显式任务态 + 相位模块 + 步骤级验证，可能比继续堆端到端动作数据更能提升 OOD 成功率。** 本轮的任务就是把这个假设变成可证伪的 UniBot 方案。

## 1. 三个灵感词，各钉到一个真问题

### 1.1 SLAM → 任务态 SLAM：不是“机器人在哪”，是“任务走到哪、东西在哪、什么变了”

G1 的基座在评测中基本固定，机器人定位不是瓶颈。真正的“where am I”是：

- **步骤定位**：我现在在第几步？上一步真的完成了吗？
- **对象定位**：任务相关物体/容器/槽位在哪？被遮挡后还在原处吗？
- **变化定位**：刚才的人为干扰移动了哪个对象？它影响了哪个已完成步骤？
- **不确定性定位**：地图有多可信？什么时候该退回端到端 VLA？

这正是 SLAM 的结构，只是把“机器人位姿 + 稠密地图”换成“对象位姿 + 关系 + 步骤信念”：

| 经典 SLAM | 任务态 SLAM |
|---|---|
| 机器人位姿 \(T_t\) | 步骤后验 \(p(s_t)\) + 主动对象 |
| 地图点/landmark | 对象 slot + 容器 + 槽位 |
| 观测模型 | 立体/腕部观测 → 对象位姿/关系 |
| 运动模型 | 动作 → 预测对象变化 |
| 回环检测 | 对象重现/重新关联 |
| 重定位 | 干扰后地图校正 + 步骤回滚 |
| 地图不确定性 | 位姿协方差/关联熵/步骤熵 → 融合门控 |

**不做稠密 SLAM 的理由**：没有 depth、180s 限时、6B VLA 已经在算力预算里；稠密重建的延迟和失败模式会把系统拖垮。桌面任务需要的是“哪个物体在哪个容器/槽位、关系是否满足”，不是毫米级稠密表面。毫米级精度交给腕部视觉伺服和柔顺控制。

**与现有 memory 工作的区别**：

- SOMA/OCC4M 主要解决“目标不在当前视野/历史被遮挡”，用 VLM 查询记忆；我们解决“官方评分步骤是否满足、被人为干扰后如何回滚”，记忆是策略的内部状态，不是外部 VLM prompt。
- DREAM 用 LiDAR/视觉 SLAM + 体素地图；我们没有 LiDAR/depth，做对象级 2.5D，避免体素/稠密重建。
- 场景图 IL 用场景图做模仿学习记忆；我们把场景图**锚定到官方 94 个评分步骤**，每个节点/边都对应可验证谓词，直接服务 success/步骤分。
- PhysMem 强调“验证后再应用”；我们把验证做成步骤级谓词 + 地图一致性检查，且验证器在单 checkpoint 内。

### 1.2 步骤分 → 语义骨架 + 字典序 + 瓶颈，而不是主目标

官方 94 个评分步骤不只是 reward，它们是**任务分解的现成标注**：

- 每个步骤给出对象、动作、目标关系（放/插/叠/合/拉/倒）；
- 每个步骤有权重，终局全是最高权重；
- 步骤顺序给出相位标签，可直接监督相位路由器；
- 步骤文本给出谓词定义，可直接监督步骤验证器；
- 步骤级成功率给出诊断向量，直接指出瓶颈。

但必须避免“步骤分陷阱”：

```text
错误：max E[Σ w_k z_k]          # 可能牺牲终局 success
正确：lex max (E[∏ z_k], E[Σ w_k z_k])
```

具体做法：

1. **训练**：success 为主损失；步骤完成为辅助/密集损失；不做“步骤分加权超过 success”的课程。
2. **选模**：验证集上按 `(success, step_score)` 字典序选 checkpoint，不按平均分。
3. **预算**：重试/计算优先给“最弱步骤”（conditional failure probability 最高），不是“权重最大步骤”；终局仍然优先，因为它是闸门。
4. **tie-break salvage**：只有在 success 已经不可能（谓词失败且无时间/重试）时，才切换到“最大化剩余步骤分”的保守模式；绝不为了步骤分放弃仍可成功的 episode。
5. **诊断**：报告 per-step success vector，而不是只报总分；用 StepEval/ManipArena 的思路做步骤级评估（[S23][S25]）。

### 1.3 模块化设计 → 单 checkpoint 内的相位/能力模块，而不是多模型堆叠

赛事规则要求“所有任务基于同一模型完成，不得混合使用多个模型”（[S1]）。这堵死了“检测器 + 抓取模型 + VLA + 世界模型”的多模型拼装，也堵死了 per-task LoRA 的部署形态。但模块化仍然有价值，只是要放在**一个 checkpoint 内部**：

| 层级 | 模块化对象 | 部署形态 |
|---|---|---|
| 表示层 | 地图 / 策略 / 验证器 | 类型化接口，全部在同一 policy 内 |
| 计算层 | 相位/能力专家、cheap/expensive path | 稀疏 MoE + 条件计算，同一 checkpoint |
| 训练层 | 分阶段训练、冻结 backbone、独立 head | 训练时分开，推理时合并 |

证据：

- PAMAE 证明 phase-aware MoE action expert 可以在保留预训练 VLA backbone 的情况下，按执行阶段分配专家，多阶段任务 +9.2%（[S18]）；
- HiMoE-VLA 证明层级 MoE 能缓解异构动作空间/观测的负迁移（[S19]）；
- RouteRLT 证明“通才默认 + 精度阶段专家接管”在物理插入任务上 65.7% vs 8.6%（[S20]）；
- Emergent MoE 证明专家会自发对应低层行为，说明相位路由有可解释性基础（[S22]）；
- CORAL 的 per-task LoRA 说明“参数隔离”能缓解任务干扰，但需要 task routing，且不解决未见任务/未见轴；我们明确**不用 per-task expert**，只用 phase/capability expert（[S21]）。

一句话：**模块化不是“多几个模型”，而是“一个模型里，不同阶段用不同计算路径，且接口可验证”。**

## 2. 本轮主判断：T-SLAM-GPR

### 2.1 一句话

**把 UniBot 当成一个任务态估计问题：用官方 94 个评分步骤构造对象级、可验证、可重定位的 2.5D 任务态地图（T-SLAM），用地图/步骤后验条件化一个单 checkpoint 的相位模块化策略（PM-MoE），用字典序验证器（LGV）保证成功率先行、步骤分只做 tie-break 和恢复信号。**

### 2.2 失败模型：端到端 VLA 的六个断点

| # | 失败模式 | 表现 | T-SLAM 对策 |
|---|---|---|---|
| F1 | 空间 grounding 错 | 选错对象/容器/槽位；位置泛化崩 | 对象 slot + 关系图 + 地图条件化 |
| F2 | 步骤状态错 | 跳步、假完成、重复做已完成的步骤 | 步骤后验 + 谓词验证 + 状态机 |
| F3 | 干扰后不恢复 | 人移动物体后继续按旧计划执行 | 变化检测 + 重定位 + 步骤回滚 |
| F4 | 终局精度不够 | 插入/堆叠/拉链最后 3cm 失败 | 地图粗定位 + 腕部伺服 + settle 验证 |
| F5 | 长程记忆丢失 | 物体被遮挡/移出视野后找不到 | 持久 track + 容器/包含关系记忆 |
| F6 | 步骤分与 success 错位 | 部分分高但终局失败 | 字典序目标 + 瓶颈优先 + tie-break salvage |

这六类里，F1/F2/F3/F5 都是“任务态”问题，不是“动作生成”问题；F4 是系统精度问题；F6 是目标函数问题。T-SLAM 主要打前四个，保留 PGL/OPT/SVL 打 F4，LGV 打 F6。

### 2.3 为什么不是三个补丁：一个闭环

```text
语言（32×5 复述）+ 官方 94 步评分图
                  │
                  ▼
        T-SLAM 任务态地图
  对象 slot / 容器 / 关系 / 步骤后验 / 不确定性
                  │  map tokens + step embedding + uncertainty
                  ▼
        PM-MoE 单 checkpoint 策略
  共享 WLA backbone + map adapter + phase router + sparse action experts
                  │  action chunk
                  ▼
        LGV 字典序验证器
```

## 4. 可证伪性与风险

- **地图假设**：若离线 held-out + 干扰场景上，地图条件化相对 base VLA 的 success 提升 <3pp，则地图降级为“仅验证/诊断”，不进入动作条件化。
- **相位 MoE 假设**：若 PM-MoE 相对 dense action expert 提升 <2pp，或路由在未见任务上崩，则退回 dense。
- **立体假设**：若 0.3–0.8m 桌面深度误差 >2cm，或透明/反光物体失败率过高，则该任务桶退回腕部/相位先验，不用地图做位姿。
- **验证器假设**：若步骤谓词 F1 <0.8，或假阳性导致 success 下降，则验证器只做诊断，不 gate 步骤前进。
- **单模型合规**：所有学习组件（backbone、LoRA、map head、step head、router、experts）在同一 checkpoint；立体/RANSAC/位姿图/HMM 是确定性算法；离线 teacher 不参与推理。若主办方仍认为辅助 head 是“多模型”，回退 C0/C1 合规阶梯（见产物区）。
- **统计风险**：320 trials 的 +3pp 不显著；不追 2–3pp，目标 +5pp；调试通道只做定性诊断，不做 A/B 显著性。
- **范围风险**：不做稠密 SLAM/全 3D 重建；只做对象级 2.5D + 关系 + 步骤谓词。

## 5. 一句话押注

**UniBot 的瓶颈不是动作生成，而是任务态估计：把官方 94 个评分步骤变成一张对象级、可验证、可重定位的任务态地图，用相位模块化单 checkpoint 执行，成功率先行、步骤分只做 tie-break 和恢复信号——这是本轮最值得押注的方向。**

## 1. 事实核对与纠偏

### 1.1 排名规则：成功率先行，步骤分是 tie-break

手册（[S1][S2]）原文要点：

- 每个任务 10 次独立运行；位置、干扰物、桌面背景、未见物品、人为干扰 5 类泛化，每类 2 次；

- 单次真机执行最大 180s，超时失败；

```text

次目标 = 步骤分（只在成功率打平时使用）
```

页面文案写“按平均成功率与步骤分综合排序”，与手册的字典序表述不完全一致；**以手册为准**，并把“若实际是加权”列入开放问题。若实际加权，步骤分的权重需要重新估计，但“success 是主目标、终局是闸门”的结论不变。

## 2. 问题形式化

### 2.1 任务态 POMDP

把每个 episode 写成部分可观测马尔可夫过程：

```text
状态 x_t = (M_t, s_t, z_t, θ_t)
  M_t : 对象/容器位姿、关系、可见性、地图不确定性
  s_t : 当前步骤（1..K）
  z_t : 已完成步骤向量
  θ_t : 机器人本体/夹爪状态
观测 o_t = 四路 RGB + proprio + language
动作 a_t = 双臂 EE/joint + gripper + pivot（chunk）
```

策略：

\[
\pi_\theta(a_t \mid o_{\le t}, l, M_t, p(s_t), u_t)
\]

地图更新：

\[
M_t = f_\theta(M_{t-1}, o_t, a_{t-1})
\]

步骤后验：

\[
p(s_t \mid M_t, l) \propto p(M_t \mid s_t, l)\sum_{s_{t-1}}p(s_t\mid s_{t-1})p(s_{t-1}\mid M_{t-1},l)
\]

### 2.2 字典序目标

设 \(S=\prod_{k=1}^K z_k\)，\(R=\sum_k w_k z_k\)。排名键：

\[
\max_\pi \left( \mathbb{E}[S],\; \mathbb{E}[R] \right)_{\text{lex}}
\]

训练时用 success 主损失 + 步骤辅助损失；选模时按 `(success_val, step_score_val)` 字典序，不按平均分。

### 2.3 AND/SUM 错位与瓶颈优先

- 若某步 conditional failure 高，success 会被它卡死；步骤分只扣该步权重。
- 若终局失败，前面所有步骤分仍在，但 success=0；这正是“步骤分高、成功率低”的来源。
- 瓶颈优先级：

\[
b_k = P(\text{reach }k)\,(1-P(\text{complete }k\mid \text{reach }k))
\]

重试/计算预算优先给 \(b_k\) 最高且 \(w_k\) 不低的步骤；终局 \(b_K\) 默认最高优先。**不要按权重分配 success 预算**。

### 2.4 统计功效

- 320 trials，p=0.30：\(SE=\sqrt{0.3\cdot0.7/320}=2.56\)pp；95% CI 约 ±5.0pp。
- +5pp ≈ 1.95 SE；+3pp ≈ 1.17 SE。**+3pp 不能靠一次总榜证明**；用配对 bootstrap/SAVI，或看步骤级/干扰子集的密集信号（[S24]）。
- 每任务 10 trials：p=0.5 时 SE≈15.8pp；p=0.3 时 SE≈14.5pp。调试槽只能定性。
- 结论：主实验目标 +5pp；早期用离线 held-out/步骤级指标；不要被 2–3pp 波动带走。

### 2.5 为什么是任务态估计，而不是更大 VLA

- 端到端 VLA 在分布内动作生成已经很强；OOD 失败更多来自“看错对象/忘记状态/被干扰后不恢复/最后 3cm 不验证”。
- 公开证据：SOMA/OCC4M 显示持久对象记忆显著改善 out-of-view/长程（[S12][S13]）；DREAM 显示动态环境需要重定位/地图校正（[S14]）；场景图 IL 用动态场景图做显式记忆（[S15]）；FOUND-IT++ 把单目 3D 场景图接进移动操作，支持变化检测/多次建图（[S16]）；PhysMem 显示“验证后再应用”比直接检索更可靠（[S17]）。
- UniBot 的特殊性：官方步骤已知、对象/容器/关系可枚举、桌面场景可 2.5D 化、基座固定——这正是轻量任务态 SLAM 的理想条件。
- 因此本轮不与头部拼“更大预训练”，而是拼“更显式的任务态 + 更合适的计算路径”。

### 2.6 头部公开做法与空白（只读技术报告，不读占位数字）

- **MolmoAct2**：开放 action reasoning model，MolmoER 骨干、OpenFAST 动作 tokenizer、双腕数据；重点是部署可用性/延迟，不是“官方步骤状态 + 干扰后回滚”（[S27]）。
- **WALL-OSS-0.5**：4B、20+ 形态、每 epoch 100 万+ 轨迹、预训练即有零样本行为；说明预训练解决“会不会”，不直接解决“最后 3cm 准不准、第几步了”（[S28]）。
- **DreamZero**：14B world-action model，2× 泛化、7Hz 闭环；强在物理动态/泛化，算力成本高，且不提供步骤级验证（[S29]）。
- **GigaBrain-0**：世界模型造数据（video/real2real/human/sim2real）、RGBD、embodied CoT；强在数据多样性，不是持久对象地图（[S30]）。
- **RoboChallenge table_30**：公共桌面榜显示单任务可以被专用模型做到很高成功率，但 UniBot 是 32 任务通才 + 5 轴泛化 + 单模型，不能直接横比（[S31]）。
- **Humanoid Everyday / UMI-Bench**：前者说明人形数据多样性/任务覆盖仍稀缺（10.3k 轨迹、260 任务；[S33]）；后者强调真实桌面评测的数据-部署-记录一体化协议（[S34]）。

**空白**：公开头部系统里，没有一个把“官方 94 步评分图 + 对象级任务态地图 + 相位 MoE + 字典序验证”做成单 checkpoint 的 UniBot 方案。它们分别在预训练规模、世界模型、数据生成、单任务精度上强；我们押“任务态 + 恢复 + 模块化”的差异化。

## 3. 失败模型与设计原则

### 3.1 六类断点

| # | 失败模式 | 典型表现 | 主对策 | 备选 |
|---|---|---|---|---|
| F1 | 空间 grounding | 选错对象/容器/槽位；位置泛化崩 | T-SLAM 对象 slot/关系 | PGL 锚点 |
| F2 | 步骤状态 | 跳步、假完成、重复步骤 | TSL + LGV 谓词 | SSG 状态机 |
| F3 | 干扰恢复 | 人移动物体后按旧计划执行 | 变化检测 + 重定位 + 回滚 | NRB 恢复策略 |
| F4 | 终局精度 | 插入/堆叠/拉链最后 3cm 失败 | 腕部伺服 + SVL | 柔顺/重试 |
| F5 | 长程记忆 | 物体被遮挡/移出视野后找不到 | 持久 track + 包含关系 | 扫描/重观察 |
| F6 | 目标错位 | 步骤分高但 success 低 | 字典序 + 瓶颈优先 | tie-break salvage |

### 3.2 设计原则

1. **地图只在可信时进入动作条件化。** 地图不确定性高时退回 base VLA；地图只做验证/诊断。避免“地图错得自信”把策略带偏。
2. **验证器保守。** 假阳性（提前前进）比假阴性（多试一次）更伤 success；阈值不对称，要求连续帧 + 稳定性。
3. **成功率先行。** 步骤分只做辅助/tie-break；不为部分分牺牲可成功的 episode。
4. **单 checkpoint。** 所有学习组件在同一模型；确定性算法不算模型；离线 teacher 不参与推理。
5. **不做稠密 3D。** 对象级 2.5D + 关系 + 步骤谓词；毫米级交给腕部。
6. **不按任务分专家。** 路由按相位/能力/不确定性，不输入 task ID；避免 OOD 任务无法路由。
7. **官方步骤是语义层。** 94 步文本/权重直接变成相位标签、谓词、诊断向量。
8. **每一步都有 fallback。** 地图→base VLA；MoE→dense；LGV→诊断；立体→腕部/相位先验。

## 4. T-SLAM：对象级任务态地图

### 4.1 表示

\[
M_t = (O_t, R_t, s_t, z_t, U_t)
\]

| 元素 | 内容 | 维度/说明 |
|---|---|---|
| \(O_t\) | 对象 slot \(o_i=(T_i^B,\Sigma_i,v_i,c_i,\text{id}_i)\) | 位姿、协方差、可见性、置信度、track id |
| \(R_t\) | 关系 \(r_{ij}\in\{\text{on,in,left,right,front,back,stacked,inserted,closed,zipped}\}\) | 概率边；几何规则 + 学习头 |
| \(s_t\) | 步骤后验 \(p(s_t=k)\) | 每任务 K=2–5 |
| \(z_t\) | 步骤完成向量/谓词概率 | 94 步定义 |
| \(U_t\) | 不确定性 | 位姿协方差、关联熵、步骤熵、可见性 |

容器/槽位作为特殊对象：容器有局部坐标系 \(T_R^B\)；放置位姿用容器系表达 \(T_G^R=(T_R^B)^{-1}T_G^B\)，与第 7 轮 OPT 兼容。

### 4.2 感知：立体 + 对象 slot + 关系

**相机映射**：假定 `cam_left_high`/`cam_right_high` 对应数据集 `head_stereo_left/right`，腕部对应 `wrist_left/right`；第一个调试 episode 用同一场景核对（图像内容/视差/基线）。若映射不对，用 API 图像做自标定或退回单目+腕部。

**立体深度**：

1. 用数据集 `camera_params` 做 rectify（已 `rectified=true`，仍做一致性检查）；
2. SGBM/ELAS 在 320×480 或 480×640 上算视差；亚像素插值；
3. 反投影到 base 系：\(Z=fb/d\)，\((X,Y)=((u-c_x)Z/f,(v-c_y)Z/f)\)，再用头部外参/躯干位姿变换；
4. RANSAC 拟合桌面平面，得到桌高/法向；点数不足时用 proprio/已知桌高兜底；
5. 只在桌面平面上方 0–40cm 的带内保留点，过滤背景。

**对象 slot**：

- 任务描述给出对象清单（杯/碗/水果/工具/插头/网线/瓶子/盒子/拉链包/毛巾等）；多数有颜色/形状先验，可用颜色+几何+连通域做候选；
- 对未知/未见物品，用离线 open-vocab 检测/分割（SAM/GroundingDINO 类）生成伪标签，蒸馏到 checkpoint 内的 query-based slot head；**推理不加载这些 teacher**；
- slot head 输出：中心/包围盒/朝向/可见性/置信度；透明/反光/布料单独分桶，不用深度做位姿。

**关系**：

- `on/in/left/right/front/back/stacked` 用几何规则（桌面平面、容器内点、相对坐标、支撑关系）；
- `inserted/closed/zipped` 用腕部视图 + 相位 + 学习谓词头；
- 关系边带概率；低置信度边不进入 hard gate，只作为策略 token。

**腕部**：负责最后 3–10cm 的相对位姿、插入对准、夹爪开度/接触；不参与全局地图的厘米级定位。

### 4.3 跟踪、位姿图与回环

**数据关联**：

- 预测：用上一帧位姿 + EE 动作 + 对象速度预测当前位姿；
- 匹配：位置/外观/类别代价的匈牙利匹配；门限用马氏距离；
- 新对象：未匹配观测且置信度高 → 新建 slot；低置信度 → 暂存，连续 3 帧才确认；
- 丢失：连续 N 帧不可见 → 保留 slot（记忆），可见性下降，协方差增大；不立即删除。

**对象位姿图**：

- 节点：桌面锚点、对象、容器、左右夹爪；
- 边：立体/腕部观测的相对位姿、桌面支撑约束、容器包含约束、抓取时的夹爪-对象约束；
- 用 Gauss-Newton/Levenberg-Marquardt + Huber 鲁棒核，5–10Hz；20–40 节点，CPU/GPU 都便宜；
- 不做全局 BA/稠密地图；只优化任务相关子图。

**回环/重定位**：

- 对象重新出现：把新观测与旧 track 关联，若位姿残差 > \(\tau_{\text{loop}}\)，加回环边并校正；
- 人在机器人未抓取时移动对象：把该对象的旧因子降权/重置，标记 `moved_by_human`；若它关联已完成步骤，回滚该步骤；
- 重定位失败：清空该对象 track，重新检测；策略退回 base VLA + 重观察（头部扫描/腕部查看）。

### 4.4 步骤定位（TSL）

对每个任务，步骤图是线性链 \(1\to2\to\dots\to K\)，允许 stay/advance/rollback：

\[
p(s_t\mid M_t,l)\propto p(M_t\mid s_t,l)\sum_{s_{t-1}}A_{s_{t-1},s_t}p(s_{t-1}\mid M_{t-1},l)
\]

- 转移矩阵 \(A\)：stay 0.8、advance 0.18、rollback 0.02（按任务/阶段调）；终局前 advance 更保守；
- 观测似然 \(p(M_t|s_t,l)\)：LGV 谓词头 + 关系一致性 + 对象可见性；
- 输出不是 hard state，而是后验；策略/路由器用后验 + 熵；
- 熵高 → 不 gate 前进，只做重试/观察；熵低且谓词高 → 前进。

### 4.5 动作耦合与变化检测

- 策略输出动作 chunk 时，地图模块用同一动作做“预测地图” \(\hat M_{t+1}\)；
- 执行后比较 \(\Delta_t=d(M_{t+1},\hat M_{t+1})\)（对象位移/关系翻转/可见性变化）；
- \(\Delta_t\) 高且不是机器人主动抓取 → 触发重定位/重规划；
- 已完成步骤的谓词从 1→0 → 回滚到最早受影响步骤；NRB 恢复策略接管；
- 这相当于“任务态回环”：不是机器人位姿回环，而是对象/步骤一致性回环。

### 4.6 不确定性门控

\[
u_t = w_1\,\text{tr}(\Sigma) + w_2\,H(\text{association}) + w_3\,H(s_t) + w_4\,(1-\text{visibility})
\]

- \(u_t<\tau_{\text{low}}\)：地图 token 全量进入策略；
- \(\tau_{\text{low}}\le u_t<\tau_{\text{high}}\)：只把高置信对象/关系作为 token，低置信度不进；
- \(u_t\ge\tau_{\text{high}}\)：地图只做验证/诊断，策略走 base VLA；同时触发重观察。
- 训练时做 map dropout（随机置零/加噪），防止策略过度依赖完美地图。

### 4.7 复杂度与延迟

| 模块 | 频率 | 预算 |
|---|---:|---:|
| 立体 rectify + SGBM | 10–15Hz | 10–20ms |
| 对象 slot/关系 | 10Hz | 10ms |
| 位姿图 | 5–10Hz | 5ms |
| 步骤 HMM | 30Hz | <1ms |
| 策略（6B, chunk 8–16） | 3–5Hz | 100–200ms/chunk |
| 腕部伺服/验证 | 30Hz | 与控制同周期 |

目标：地图总延迟 <30ms；策略 p99 <200ms/chunk；整体在 180s 内可完成 1–2 次重试。若策略延迟过高，降分辨率/量化/减 expert；不牺牲地图频率。

## 5. PM-MoE：单 checkpoint 的相位模块化策略

### 5.1 Backbone 与 adapter

- 底座：WLA-1.0-Base（约 6B，Apache-2.0；[S32]），保留第 7 轮 GPR-VLA 的 flow-matching action expert 接口；24GB 级 LoRA 微调需按实际配置复核；
- LoRA：rank 64/alpha 128，冻结 backbone；action expert 可全量或 LoRA；
- **Map adapter**：把对象 slot/关系/步骤后验/不确定性投影成 32–64 个 map tokens，通过 cross-attention 注入视觉/语言 token；map token 数量有界，避免长上下文；
- **Step embedding**：\(e_{s_t}=\sum_k p(s_t=k)e_k\)，把官方步骤文本编码 + 权重 + 相位类型（reach/grasp/transport/place/insert/close/recover）拼成 embedding；
- **Role tokens**：左右臂角色 token（hold/insert/support），支持双手协作；不另起模型。

### 5.2 相位路由器与稀疏专家

\[
g_t=\text{TopK}\left(\text{softmax}\left(W_r[h_t;e_{s_t};u_t;l]\right)\right)
\]

- \(h_t\)：共享视觉/语言/proprio token 的池化；
- \(e_{s_t}\)：步骤 embedding；\(u_t\)：地图不确定性；\(l\)：语言；
- 4 个 action experts（每个约 32–64M，flow-matching head），Top-1 或 Top-2；
- 专家按**相位/能力**划分，不按任务：reach/grasp、transport/place、insert/close、recover/bimanual；
- 路由器不输入 task ID；任务信息只通过语言/步骤图进入，保证未见任务可路由；
- 低置信度（max gate < \(\tau_g\)）或步骤熵高 → 走 dense fallback expert；
- 负载均衡损失 + 相位对齐损失（路由分布与步骤标签一致）。

### 5.3 训练

两阶段（参考 PAMAE [S18]）：

1. **Warmup**：dense action expert + flow-matching loss；冻结/轻调 backbone；让动作头适配 G1+Dex1。
2. **Phase routing**：加入专家、路由器、相位标签；路由对齐 + 负载均衡；再联合微调 LoRA。
3. **Map-conditioned fine-tune**：加入 map adapter，训练时用预测地图（不是 GT）并做 map dropout；避免 exposure bias。
4. **Disturbance fine-tune**：加入 NRB/重定位/回滚样本；训练策略在谓词翻转后的恢复。
5. **Deployment**：蒸馏/量化/合并 LoRA；单 checkpoint 导出。

损失：

\[
L=L_{\text{flow}}+\lambda_1L_{\text{succ}}+\lambda_2L_{\text{step}}+\lambda_3L_{\text{map}}+\lambda_4L_{\text{rel}}+\lambda_5L_{\text{route}}+\lambda_6L_{\text{bal}}
\]

| 项 | 含义 | 起始权重 |
|---|---|---:|
| \(L_{\text{flow}}\) | 动作 flow matching | 1.0 |
| \(L_{\text{succ}}\) | 终局 success 预测/成功加权 | 0.2 |
| \(L_{\text{step}}\) | 步骤完成 BCE | 0.2 |
| \(L_{\text{map}}\) | 对象位姿/关键点/跟踪 | 0.1 |
| \(L_{\text{rel}}\) | 关系 BCE | 0.1 |
| \(L_{\text{route}}\) | 相位分类/路由对齐 | 0.05 |
| \(L_{\text{bal}}\) | 专家负载均衡 | 0.01 |

权重不是重点；重点是 **success 为主、步骤为辅、地图做条件**。训练时随机 drop map token/加噪，推理时用真实地图。

### 5.4 双手协作

- 32 任务里 T05/T10/T26 等需要“扶住/固定 + 插入/拔出”；T16/T17/T18/T19/T23/T31 需要双手/协同；
- 地图给左右夹爪各自的对象/容器关系；role token 让专家知道“哪只手负责 hold、哪只手负责 insert”；
- 不训练独立的“左手模型/右手模型”；同一 checkpoint 输出双臂 action chunk。

### 5.5 为什么是单模型

- 一个 policy checkpoint 包含：backbone、LoRA、map encoder、step head、router、experts；
- 立体/RANSAC/位姿图/HMM/迟滞是确定性算法，不是“模型”；
- 离线 teacher（SAM/GroundingDINO/VLM）只生成标签，不部署；
- 没有 per-task 权重、没有模型集成、没有外部 API 推理；
- 模型卡逐项披露学习组件与确定性组件（见 §9.6）。

### 5.6 证据与差异

| 工作 | 做法 | 结果 | 我们的差异 |
|---|---|---|---|
| PAMAE [S18] | phase-aware MoE action expert，保留 VLA backbone | 多阶段任务最高 +9.2% | 路由加入地图不确定性/步骤后验；单 checkpoint 含 map adapter |
| HiMoE-VLA [S19] | 层级 MoE 处理异构动作空间/观测 | CALVIN 3.98、LIBERO 98.0% | 不做 action-space 分层，做 phase/capability 路由 |
| RouteRLT [S20] | 通才 + 精度阶段 RL 专家接管 | 物理 connector 65.7% vs 8.6% | 不引入独立 RL 专家；专家在同一 checkpoint，避免多模型 |
| CORAL [S21] | 每任务 LoRA expert + task routing | 缓解多任务干扰 | 明确不用 per-task；用 phase routing 保证 OOD |
| Emergent MoE [S22] | 简化 MoE 自发形成低层行为专家 | 与 monolithic 持平、可解释 | 用官方步骤显式监督路由，减少“自发但不稳定” |

## 6. LGV：字典序验证器与恢复

### 6.1 步骤谓词

94 个步骤按类型分：

| 类型 | 例子 | 验证信号 |
|---|---|---|
| 抓取/取出 | 抓杯、抓插头、挑电池 | 夹爪闭合 + 对象随动 + 腕部接触 |
| 放置/堆叠 | 放碗、叠杯、放架 | 对象位姿进入容器/槽位容差 + 支撑/稳定 |
| 插入/拔出 | 插头、网线、试管 | 相对位姿 + 插入深度 + 腕部视图 |
| 闭合/拉链 | 合盖、拉拉链、锁箱 | 腕部视图 + 关系谓词 + 动作完成 |
| 倒/挤/吸 | 倒药、注射器 | 容器位姿 + 液体/腕部视图（分桶） |
| 排序/拼写 | 颜色顺序、拼 robot | 多对象关系 + 顺序约束 |

- 谓词头 \(p_k=\sigma(f_\theta(M_t,k))\)，输入地图 + 视觉 + 步骤 embedding；
- 几何类谓词用确定性规则 + 学习残差；变形/透明类用腕部 + 相位先验；
- 用 held-out 校准阈值；**以 success 为目标选阈值，不以 F1 为目标**（假阳性代价更高）。

### 6.2 状态转移与迟滞

```text
advance:  p_k > τ+ (0.9) for 2 consecutive frames
          AND relation stable for 0.5s
hold:     otherwise; retry current step
rollback: p_k < τ- (0.2) for 3 frames
          AND object moved/relation broken
          AND step was previously completed
```

- 迟滞避免谓词抖动导致步骤来回跳；
- rollback 只回滚到最早受影响步骤，不整任务重来；
- 回滚后保留地图/已完成的其他步骤，减少重复工作；
- 若验证器不确定，不 gate 前进；策略继续执行，但记录诊断。

### 6.3 重试/计算分配

- 每任务重试预算：普通 ≤2 次；长程（T16/T17/T31）≤1 次；总时长守卫兜底；
- 预算优先给 \(b_k\) 最高步骤；终局优先；
- 每次重试前用地图诊断（对象丢了/关系不对/夹爪没夹住），选择 nudge/regrasp/replan，不做盲目重放；
- 若地图不确定，先重观察（头部扫描/腕部查看），再决定重试。

### 6.4 tie-break salvage

```text
if P(success | M_t) < ε and T_remaining > T_min:
    maximize E[Σ_{j≥s_t} w_j z_j]   # 只拿剩余步骤分
else:
    maximize P(success)             # 成功仍可能，绝不放弃
```

- 触发条件保守：终局谓词已失败/对象不可恢复/时间不足以完成终局；
- 用途：在成功率相同的榜单上争 tie-break；
- 不能用来“刷步骤分”而牺牲仍可成功的 episode；这是字典序的硬约束。

### 6.5 选模

\[
\theta^*=\arg\max_\theta \left(\text{Success}_{\text{val}}(\theta),\text{StepScore}_{\text{val}}(\theta)\right)_{\text{lex}}
\]

- 验证集要覆盖 5 轴 + 干扰；不能只看平均；
- 若两个 checkpoint success 相同，选 step score 高者；
- 不选“步骤分高但 success 低”的模型；
- 报告 per-step success vector，定位瓶颈（[S23][S25]）。

### 6.6 恢复与 NRB

- 用官方 human 备注构造破坏→恢复对（1-DOF 平移/撤销）；
- 训练策略在谓词翻转后回滚、重定位、恢复；
- 恢复动作库：nudge/regrasp/replan/reobserve；
- 若恢复失败，退回 base VLA 重新执行当前步骤；
- NRB 只在训练数据，不增加推理模型。

### 6.7 地图条件化的 PGL/OPT/SVL

保留第 7 轮：

- **PGL**：槽位/区域 → 2D 锚点 → 6D 位姿；地图提供容器/槽位位姿；
- **OPT**：K 条演示的容器系释放位姿中位数 + 离散度；地图提供当前容器系；
- **SVL**：伺服→缓放→稳定性/谓词校验→nudge/regrasp/retry；
- 升级：容器位姿来自 T-SLAM（而非单帧检测），遮挡/移动后仍可用；LGV 决定是否重试。

## 7. 数据与标签

### 7.1 默认只用官方数据

- 官方 32 个数据集、约 33k episodes、169h（[S6]）；
- 外部数据/自采/仿真默认 OFF；先邮件确认规则；
- 离线 teacher（SAM/GroundingDINO/VLM）只生成标签，不部署；若规则不允许，改用颜色/几何/人工标注；
- 预训练权重（WLA）合规性需确认；若不允许，退回官方可用的开源底座。

### 7.2 步骤边界标签

- 94 个步骤；每个任务 `info.json` 有 5 条示例 episode（32×5=160 条）；
- 人工/VLM 辅助标注这 160 条的步骤边界（约 1 周，3 人）；
- 用 DTW/动作相位/夹爪事件把边界传播到全量 33k；抽检 10%；
- 产出：每帧步骤标签、每步开始/结束、谓词正负样本；
- QA：边界误差 <0.5s；步骤覆盖 100%；异常 episode 剔除。

### 7.3 对象/关系标签

- 任务描述给出对象清单；颜色/形状/位置先验；
- 离线分割/检测生成 5k 帧伪标签；人工抽检 10%；
- 训练 checkpoint 内的 slot head/关系头；推理不加载 teacher；
- 透明/反光/布料分桶：不用深度做位姿，只用腕部/相位/外观。

### 7.4 干扰/恢复样本

- 64 条 human 备注（32 任务 × 2）；每条生成 1-DOF 平移/撤销场景；
- 每个场景 50 条，约 3,200 条；刚体/容器优先；布料/拉链只做轻量增强；
- 可选：用 2.5D 合成/回放，不追求全物理；
- 若外部/仿真不允许，只用真实数据 + 图像编辑/回放，主方案仍可跑。

### 7.5 数据预算

| 项 | 规模 | 用途 | 成本 |
|---|---:|---|---|
| 官方真实数据 | ~33k episodes | 主训练 | 已有 |
| 步骤边界标注 | 160 episodes | 相位/谓词监督 | 1 周 ×3 人 |
| 对象/关系伪标签 | ~5k 帧 | slot/关系头 | 3–5 天 |
| 干扰/恢复 | ~3.2k | 重定位/回滚 | 1 周（可选） |
| 地图/步骤头训练 | — | 辅助头 | 8×H100 2–3 天 |
| 策略 LoRA/PM-MoE | — | 主策略 | 8×H100 2–3 周 |

## 8. 训练配方

### 8.1 阶段

| 阶段 | 数据 | 训练 | 退出条件 |
|---|---|---|---|
| 0 | 官方真实 | 复现 WLA/GPR 基线 | held-out 不降 |
| 1 | +步骤边界 | 步骤头/谓词头 | 步骤 F1 ≥0.8 |
| 2 | +对象/关系伪标签 | slot/关系头 | 位姿误差 <2cm（桌面） |
| 3 | +地图 token | map adapter + LoRA | 地图条件化 +3pp 离线 |
| 4 | +相位标签 | PM-MoE 两阶段 | 相对 dense +2pp |
| 5 | +干扰/恢复 | 重定位/回滚 | 恢复 >50% |
| 6 | 全量 | 联合微调/蒸馏/量化 | 延迟/稳定性达标 |

### 8.2 超参（沿用第 7 轮，增量）

- WLA-1.0-Base（约 6B）；LoRA rank 64/alpha 128；action expert 全量或 LoRA；
- AdamW；lr 1e-4（LoRA）/2e-5（全量）；cosine；warmup 3%；
- global batch 64–128；bf16；chunk 8–16；horizon 1–2s；
- 早停看 held-out success + 干扰子集，不看训练 loss；
- PM-MoE：4 experts，top-1/top-2；负载均衡 0.01；相位对齐 0.05；
- 地图 dropout 0.1–0.3；map token 32–64。

### 8.3 算力

- 地图/步骤/关系头：8×H100 约 2–3 天；
- 策略 LoRA + map adapter：8×H100 约 2 周；
- PM-MoE：+1 周；
- 干扰/恢复微调：3–5 天；
- 推理：单张 H100/L40S 可跑 6B bf16；24GB 需量化/蒸馏；若只有 24GB，先做 C0/C1（地图+验证器，不重训大模型）。

### 8.4 避免 exposure bias

- 训练时地图 token 来自预测地图（不是 GT），并加噪/dropout；
- 逐步增加地图噪声，模拟立体误差/遮挡/干扰；
- 评估时同时测“完美地图/预测地图/无地图”三种，量化依赖；
- 若预测地图显著差于完美地图，先改地图，不要加 MoE。

```python
    "observation.state.left_ee_pose_gripper_base": [-4, -2, 0],
    "observation.state.right_ee_pose_gripper_base": [-4, -2, 0],
    "observation.state.left_gripper": [-4, -2, 0],
    "observation.state.right_gripper": [-4, -2, 0],

  },

    "observation.images.cam_right_wrist": [240, 320]

  "token": "..."
}
```

- 高位保持 480×640（或 320×480）供立体；策略内部可再降采样。腕部可 240×320 或 320×240；若插入任务需要更高分辨率，腕部用 480×640（延迟换精度）。
- `control_space` 选 `ee`：地图条件化的放置/插入用 EE 位姿更直接；若调试发现 joint 更稳，再切 joint（需重训/重标定）。
- `action_chunk_size` 8–16；太大降低纠错频率，太小增加推理次数。

### 9.2 相机映射与自检

- 启动时检查四路图像尺寸/内容；用同一场景核对高位左右视差与腕部视角；
- 若 API 相机与数据集命名不一致，用图像内容/机械安装关系映射；
- 若无法获得相机内参，用数据集参数 + 固定安装假设；调试槽用已知物体尺寸做尺度校验；
- 立体失败（纹理少/反光）→ 单目 + 桌面平面 + 腕部；地图置信度下降。

### 9.3 延迟预算

| 路径 | 目标 | 备注 |
|---|---:|---|
| 地图（立体+slot+pose graph+HMM） | <30ms | 10Hz 异步 |
| 策略 chunk | <200ms p99 | 6B bf16；chunk 8–16 |
| 有效控制 | 3–5Hz | 180s 足够 |
| 重试/恢复 | ≤2 次/任务 | 长程 ≤1 次 |

若延迟超标：降图像分辨率、减 map token、量化、减 expert、缓存视觉特征；不牺牲安全/验证。

### 9.4 每 episode 状态与多端口

- `reset()` 清空地图、步骤后验、track、重试计数；不能跨 episode 记忆；
- 每个端口/会话独立 state；共享模型权重可以，state 不能共享；
- 服务端用 session id/episode id 隔离；并发请求批处理，但地图状态按会话；
- 健康检查/超时/重连；失败时返回安全动作/重试，不崩服务。

### 9.5 单模型合规阶梯

| 级别 | 内容 | 风险 | 用途 |
|---|---|---|---|
| C0 | base VLA + 确定性步骤图/验证器（无地图） | 最低 | 合规兜底 |
| C1 | + 经典立体对象地图（无学习地图头） | 低 | 最小可行 |
| C2 | + 学习地图/步骤头（同一 checkpoint） | 中 | 主方案 |
| C3 | + PM-MoE（同一 checkpoint） | 中 | 主方案 |

若主办方对“学习辅助头是否算多模型”有疑问，回退 C0/C1；C0/C1 仍保留步骤图、验证器、经典地图，已经能打 F1/F2/F3 的一部分。

## 10. 评测协议

### 10.1 离线指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 对象位姿误差 | 桌面对象中心/朝向 vs 人工标注/仿真 GT | <2cm / <10° |
| track ID switches | 每 episode 关联错误次数 | <1 |
| 关系 F1 | on/in/left/right/stacked/closed 等 | >0.85 |
| 步骤 F1 | 94 步完成谓词 | >0.80 |
| 重定位成功率 | 干扰后 N 帧内恢复 | >70% |
| 假回滚率 | 未干扰却回滚 | <5% |
| 下游 success | held-out 回放/仿真/真机 | +3pp vs base |
| 延迟 | 地图/策略 p99 | <30ms / <200ms |

对象位姿 GT 有限：用人工标注子集（每任务 10 episodes）+ 仿真 + 下游 success 作为主终点；不假装有全量 GT。

### 10.2 调试槽协议（定性）

- 每个大版本最多 1–2 槽；首选 T27（叠碗=放置/堆叠）、T10（插排=插入/力控）、T19（拉链=闭合）、T24（传送带=移动目标）；
- 每槽跑 5 个脚本化场景：正常、位置偏移、干扰物、目标移动、撤销；
- 记录视频、失败类型、步骤级结果；**不做统计显著性声明**；
- 目的：发现地图/验证器/恢复的定性失败，不是证明 +10pp。

### 10.3 主实验（320 trials）

- 主指标：32 任务平均 success；
- 次指标：平均步骤分、per-step success vector；
- 分层：5 轴 × 任务难度；报告每轴/每步；
- 统计：配对 bootstrap（同任务/同轴）或 SAVI 序贯检验（[S24]）；报告 95% CI；同时警惕 shortcut、统计不显著、creeping overfitting、数据源依赖（[S26]）；
- 目标 +5pp；+3pp 只能作为方向性证据，需配对/SAVI/分层支持；只有 CI 不跨 0 才宣称显著。

### 10.4 消融

| ID | 配置 | 验证 |
|---|---|---|
| E0 | WLA/GPR 基线 | 复现 |
| E1 | + 步骤图/验证器（无地图） | F2/防假完成 |
| E2 | + 经典立体地图（无学习头） | F1/F5 |
| E3 | + 学习地图/步骤头 | 地图条件化增益 |
| E4 | + PM-MoE | 相位模块增益 |
| E5 | + 干扰/重定位训练 | F3 |
| E6 | + 字典序选模/salvage | F6/tie-break |
| E7 | 全量 + 蒸馏/量化 | 部署 |

补充消融：地图 on/off、map dropout、立体 vs 单目、HMM vs 固定步骤、router phase vs task vs random、专家数 1/2/4/8、验证器阈值、重试预算、干扰训练、字典序 vs 加权。

### 10.5 Go/No-Go

| 周 | 门槛 | 不达标动作 |
|---|---|---|
| W2 | 立体深度 <2cm（0.3–0.8m）；步骤 F1 ≥0.8 | 地图降级为腕部/相位先验 |
| W3 | 地图条件化 +3pp 离线 | 地图只做验证/诊断 |
| W4 | PM-MoE +2pp vs dense；p99 <200ms | 退回 dense |
| W5 | 干扰恢复 >50%；无 success 回归 | 缩到 C1 |
| W7 | 主实验 +3pp（目标 +5pp） | 回退最佳 checkpoint |
| W8 | 稳定/合规/延迟 | 提交保守版 |

## 11. 创新点清单

> 状态：押注=本轮主线；升级=旧点改造；保留=沿用；使能=基础设施；砍=不做。

### I1 T-SLAM 对象级任务态地图（押注）
- 动机：VLA 反应式，缺持久对象/关系/步骤状态；OOD 位置/遮挡/干扰需要地图。
- 差异：不是机器人 SLAM/稠密 3D，而是对象级 2.5D + 官方步骤谓词 + 不确定性门控。
- 可行性：立体标定已有；桌面 20–40 对象；位姿图/HMM 便宜。
- 资源：8×H100 2–3 天；1 人 2 周。
- 步骤：标定→slot/关系→位姿图→步骤 HMM→不确定性。
- 风险：透明/反光/布料失败 → 分桶回退。
- 证伪：干扰 held-out <3pp → 只做验证。

### I2 TSL 步骤定位/回环/重定位（押注）
- 动机：步骤状态错、假完成、干扰后不恢复。
- 差异：把“回环”从机器人位姿改成对象/步骤一致性；官方 94 步是语义层。
- 可行性：HMM + 谓词头 + 变化检测；不需要全局 BA。
- 资源：1 人 1–2 周。
- 步骤：转移矩阵→谓词似然→回滚→重定位。
- 风险：谓词噪声 → 迟滞/保守阈值。
- 证伪：重定位 <50% → 缩到步骤状态机。

### I3 PM-MoE 相位模块化（押注）
- 动机：多任务负迁移；单一 action expert 难覆盖 reach/grasp/insert/close/recover。
- 差异：按相位/能力路由，不按 task ID；单 checkpoint；地图不确定性参与路由。
- 可行性：PAMAE/HiMoE/RouteRLT 证据；4×32–64M 专家，训练成本可控。
- 资源：+1 周训练；8×H100。
- 步骤：dense warmup→phase routing→map-conditioned→disturbance。
- 风险：路由过拟合/负载不均 → 负载均衡/fallback。
- 证伪：相对 dense <2pp → 退回 dense。

### I4 LGV 字典序验证器（押注）
- 动机：success 是主目标，步骤分只 tie-break；假完成/早前进伤 success。
- 差异：验证器以 success 为目标校准，不以 F1；tie-break salvage 只在 success 不可能时触发。
- 可行性：94 步谓词 + 几何/腕部；规则+学习混合。
- 资源：1 人 1–2 周。
- 步骤：谓词→校准→迟滞→回滚→salvage。
- 风险：假阳性 → 高阈值/连续帧。
- 证伪：F1 <0.8 → 只做诊断。

### I5 立体度量层（使能）
- 动机：无 depth，但高位立体可给 2.5D；避免额外传感器/模型。
- 差异：经典立体 + 桌面平面 + 对象 slot；不训练深度大模型。
- 可行性：标定已有；误差 4–15mm@0.5m。
- 资源：CPU/GPU 5–10ms。
- 风险：纹理少/反光 → 单目/腕部。
- 证伪：>2cm → 地图降级。

### I6 地图条件化 PGL/OPT/SVL（升级）
- 动机：第 7 轮放置模块缺持久容器/槽位状态。
- 差异：容器位姿来自 T-SLAM；遮挡/移动后仍可用；LGV 决定重试。
- 可行性：复用第 7 轮。
- 风险：地图错 → 置信度门控。
- 证伪：放置误差不降 → 回退单帧检测。

### I7 NRB 干扰/恢复（升级）
- 动机：human 备注是公开剧本；重定位/回滚需要训练样本。
- 差异：官方备注忠实回放 + 通用 1-DOF 扰动兜底；与 TSL 回滚联动。
- 可行性：刚体/容器便宜；布料/拉链轻量。
- 风险：备注不是评测脚本 → 同时覆盖通用扰动。
- 证伪：恢复 <50% → 缩到重试。

### I8 标签引擎（使能）
- 动机：94 步/对象/关系没有现成逐帧标签。
- 差异：160 条示例标注 + DTW 传播；离线 teacher 蒸馏；不部署 teacher。
- 可行性：1 周标注 + 3–5 天伪标签。
- 风险：标注噪声 → 抽检/QA。
- 证伪：步骤 F1 <0.8 → 增加人工。

### I9 评测协议（使能）
- 动机：320 trials 统计功效低；步骤分/干扰需要分层。
- 差异：字典序选模 + per-step vector + 配对/SAVI；调试槽只定性。
- 可行性：现有工具 + 脚本。
- 风险：真实榜单延迟 → 先用离线/代理。
- 证伪：无法区分 → 只报 CI。

### I10 保留资产（保留）
- WLA/GPR-VLA、PGL/OPT/SVL、NRB、TLE/ACP/GF、FLEET 检查单、DebugLoop。
- 不再把 FLEET 当研究轴；不再做全 32 任务高保真孪生。

### 砍清单
- 稠密 3D/NeRF/3DGS/全 SLAM；
- per-task LoRA/模型合并；
- 推理期多模型堆叠/外部 API；
- 步骤分优先目标；
- 运行时 MPC/RL/仿真 RL；
- 自由仿真数据/全物理布料拉链透明；
- 每任务单独模型。
