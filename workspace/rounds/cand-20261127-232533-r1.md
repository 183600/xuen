## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（本体感知 → 全赛场唯一对泛化轴不变的通道）**
直觉：五条泛化轴（背景、光照、外观、位置、人手干扰）全是**外感受**的——它们改的是相机看到的世界；没有一条会改机器人「自己身体的感觉」。关节角、末端位姿、夹爪开度、下盘状态在换背景/换杯子/换位置时分布基本不动。可绝大多数 VLA 只把本体感知当成又一串拼接向量，没吃到它的不变性。重 framed：**让视觉当「提议者」，让本体感知当「裁判」**。视觉说「我大概到杯子了」，本体说「末端确实停在我指令的位置、夹爪闭合了 3cm，这一抓大概率成立」。视觉 OOD 时，裁判照样工作。
严谨化：设外感观测 x_t、本体状态 p_t、动作 a_t。在全部 32k 成功示教上自监督训练**本体前向模型** f_θ:(p_{t-h:t},a_{t-h:t})→p_{t+1}；**惊异度** e_t=(p_{t+1}−f)ᵀΣ⁻¹(p_{t+1}−f)（Mahalanobis，Σ 由标称示教残差按维/按任务估计）。成功示教上 e_t 小；打滑、碰撞、被抓空、被推会让 e_t 尖峰——**这就是无触觉传感器下的接触/打滑替代信号**。再训一个**纯本体进度头** g_p(p_{0:t},language)，它对换外观天然鲁棒；与视觉进度头 g_v 按视觉 OOD 分数融合。

**灵感 2（用户体验 → 两个「用户」，以及「可读性=流形正则」）**
直觉：这里有两个用户。(a) **组委会/评测者**：README §6 明说会看延迟稳定性与动作规律性并公开展示——抖动、异常、忽快忽慢的提交在「可信度」上先输一截（F21）；这是提交本身的 UX。(b) **在场的人**：干扰轴把真人放进工作空间，一个可读、可预测的机器人会换来合作而不是惊慌式干预。但最深的点更反直觉：**可读性不是化妆，它是「还在成功流形上」的代理。** 一条轨迹若旁观者看一小段就能高置信说出目标，它必然是典型、低熵、贴着示教分布的成功轨迹；灾难性/OOD 行为恰恰是目标含混的行为。所以「可读性」是能把策略拽回成功流形的**流形正则**，而成功流形正是步骤分所在的地方。
严谨化：对目标（=下一个官方得分点）定义可读性 L(ξ_{0:t})=−H(g|ξ_{0:t})；用示教训一个里程碑分类器 q_φ(g|ξ_{0:t},language)，在 BC 损失上加 λ·L_leg 促使「早期即可辨认目标」。**优雅失败**：当本体惊异 e_t 超阈，进入**可读恢复**（减速、后退、重观测、重抓）而非盲目续做——保住已得步骤分，且旁观者读得出「它在恢复，不是坏了」。再加一条便宜规则：**速度随不确定度下降** v∝1/(1+αe_t+β·OOD)，既安全又可读。

**两者统一（自省式 UX）**：本体感知让机器人**先于视觉知道自己要失败**，用户体验要求它**把失败处理得可读、可恢复、不砸已得进度**。合起来是「有身体自觉的策略」：内感受做裁判，外感受做提议，行为按置信度调速。与第 2 轮「数据引擎」互补：数据引擎扩大训练分布，本体裁判**不需要扩大分布**就提供不变性——一个往外铺，一个往里锚。

## 2. 对第 2 轮痛点的增量修订

- P4（无触觉）大幅下调：本体前向模型惊异度是**零新增传感器**的接触/打滑代理（F20）；与 I3 视觉伺服、I2 孪生语料构成三条互补缓解路径。
- P3（人手干扰）下调：人在保持段推/碰手臂，会造成「指令不变而关节突变」的本体残差，**先于手部视觉检测**触发让位（F20/F24）。
- P2（泛化缺口）新增一路：视觉进度在换外观时退化，纯本体进度 + OOD 融合可兜底；可读性正则把策略拉回成功流形。
- P6（部署/可信度）显式化：F21 把「交互质量」写成可被记录的指标 → I6 增加「动作健康/延迟稳定」UX 门禁。
- 新增 **P9（本体跨机漂移）**：N 台机器人关节零位/标定、`lower_body` 噪声、FK/IK 约定、夹爪机械回差可能不同——「本体不变」只是近似，是整个方案最脆的承重墙。

## 3. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

- **Q9（本体不变性的可测性）**：用「轴可辨识探针」——分别只用 p_t 与只用 x_t 训练分类器去预测当前属于哪条泛化轴/哪台机器人——若本体探针显著低于视觉探针，则不变性成立。哪些本体维度（ee 位姿 vs 原始关节 vs lower_body）最不变、最该信？
- **Q10（无触觉惊异的可校准性）**：本体前向模型惊异能否在无触觉下区分打滑/碰撞/被推/抓空与标称变化？阈值如何按任务与机器人自校准（避免「狼来了」与「装死」两端）？
- **Q11（可读性→鲁棒性的因果性）**：里程碑条件可读性正则真的提升 OOD 成功率/步骤分，还是只改了观感？需用「等强度 jerk 惩罚」作对照臂，分离「流形收缩」与「单纯平滑」的混淆。

## 4. 设计原则（新增 PR6，其余保留）

- **PR6 本体锚定律**：任何用于高风险决策（进度、失败、是否有人、是否该停）的估计，必须有本体侧交叉校验；纯视觉决策一律视为「暂定」。与 PR1（管决策）、PR5（管数据）互补，PR6 管**信任来源**。推论：优先用「对计分轴不变」的信号做裁判，优先用「对计分轴敏感」的信号做提议。
- PR1–PR5 保留（第 1/2 轮 §4）。

### I4 人手干预感知门控 + 自适应 chunk ★★★★（↑，v2）
- **本轮深化（本体感知）**：现有方案靠手部视觉检测；本轮增加**本体扰动通道**：保持/执行段若出现「动作指令平滑但关节/末端突变」的本体残差（与 I10 共用前向模型），**先于视觉**判定有人推/碰，立即进入 INTERFERED→停持→让位。视觉检测仍是第二确认，双通道投票降误报。
- **UX 调速**：干预态与 SUSPECT 态速度 `v∝1/(1+αe_t)`，动作更可读、更安全；稳定态恢复长 chunk。

### I5 非标称示教合成 + 得分点对齐恢复 ★★★★（v2.1）
- **本轮深化**：①用 I10 前向惊异度给合成示教做**自动失败/偏离标注**（扰动重放时，e_t 尖峰处即「偏离点」），省掉人工里程碑检测的一部分；②恢复由「脚本原语」改为**惊异触发的可读恢复**（I11 状态机），恢复段本身是数据分布内的减速-后退-重抓；③得分点监督保留（承接 v1.1）。

### I6 确定性低延迟部署服务 ★★★★（↑，v2）
- **本轮深化（用户体验 = 提交本身的 UX，F21）**：新增**交互质量门禁**——每步延迟 p50/p99/方差、动作二阶差分（jerk）、越界率、`float32`/形状合规纳入 PR4 门禁；延迟抖动超预算时**缩短 chunk（宁短勿乱）**，而不是返回迟滞/异常动作。
- F23 复核：N 端口逐一隔离 reset/历史状态；共享 backend 并发派发；F24 允许本体高频堆叠、图像低频，带宽预算重排。

### I7 世界模型测试时前瞻 ★★（缓）（维持）
- 同 v1.1：高险节点 O(1–2) 次小 rollout；延迟余量不足即裁撤，WMA-0 资产转 I5 数据引擎。

### I8 评测运营闭环 + 分级消融注册表 ★★★★（v2.1）
- **本轮深化**：注册表新增三类代理指标——`Δprog_proprio`（本体进度退化）、`AUROC_surprise`（惊异检测）、`UX`（延迟方差/jerk/恢复可读性）；沿用「离线代理↔真机增益」滚动 Spearman，相关性 >0.6 才准单独准入 L2。
- 新增**轴可辨识探针**为 Q9 的固定 L0 体检项，跨机/跨轴漂移早发现。

### I9 reset 期检索类比迁移 ★★★★（v2）
- **修正（F22）**：`reset()` 无观测参数，检索必须**首帧惰性触发**（首次 `get_action` 内完成），v1.1 的 `reset(first_obs)` 伪代码作废。
- **深化**：检索目标不止视觉嵌入，追加**夹爪开合签名**（该物体示教中的 gripper 开合轨迹模板）作为动作先验的一部分；误检索仍以距离阈值 + 软偏置止损。

### I10 本体感知裁判：前向惊异 + 双通道进度（新）★★★★★
- **动机**：五条泛化轴全为外感受，本体感知（F20，43 维）对它们近似不变；而数据集无触觉、全成功，策略「看不见自己的失败」（P4/P8）。需要一个**不随外观漂移的失败/进度裁判**。
- **与现有方案差异**：常规 VLA 把 proprio 当普通输入拼接，靠视觉学一切；本点把本体做成**前向模型 + 惊异度 + 纯本体进度头**，作为视觉提议的独立校验与兜底。无需新传感器、无需新数据。
- **技术可行性**：高。前向模型/进度头/里程碑分类器均可作为 action-expert 的**辅助头联合训练**（单次前向）；惊异用 Mahalanobis 残差，计算量可忽略。零推理期权重更新。
- **所需资源**：复用 32k + 110 语料；训练与 BC 同批（1×24GB 可起步）；标定 1 GPU 日；无新增下载。
- **落地步骤**：①Q9 轴可辨识探针（p vs x 分类器）；②训练本体前向模型 + 进度头；③按任务/阶段标定 Σ 与惊异阈值（Q10 AUROC）；④双通道进度融合；⑤接 I4/I5/I11 触发器；⑥L0→L2。
- **风险**：跨机标定漂移（P9）导致阈值失配——缓解：逐机器人/逐任务白化，先探针后放量；前向模型在快速段误报——缓解：按相位（接近/接触/搬运）分模型或分阈值，并加滞回。

### I11 可读性正则 + 优雅失败（新）★★★★
- **动机**：步骤分逐点累加，灾难性续做会砸掉已得进度（P1/P5）；同时组委会记录动作规律性与延迟，行为可读性影响可信度（F21）；干扰轴下可读=更少惊慌干预（P3）。
- **与现有方案差异**：常规做法只优化成功率/BC 似然；本点加**里程碑条件可读性正则**（早期即可辨认目标）与**惊异触发的可读恢复状态机**，并把速度与不确定度绑定。可读性被当作「成功流形正则」，不是事后美化。
- **技术可行性**：中-高。里程碑分类器与进度头同源（官方得分点/相位标签）；状态机是纯规则；速度律是标量缩放。
- **所需资源**：1 人周工程；分类器/正则训练与 BC 同批；无新增数据。
- **落地步骤**：①里程碑/相位标签（承接 I5 得分点逆向）；②可读性分类器 q_φ 与正则；③等强度 jerk 对照臂（分离因果）；④优雅失败状态机 + 滞回/冷却；⑤速度律；⑥L0 消融→L2。
- **风险**：正则牺牲动作似然导致成功率下降——缓解：λ 小、单独消融、以「OOD 成功率」而非「TTGI」作主判据；状态机抖动——缓解：滞回 + 冷却 + 只在 SUSPECT/RECOVER 态调速；「可读」定义主观——缓解：用里程碑分类器的 held-out 准确率/识别时间作客观代理。

```python
# a_t: joint = L_arm(7)+R_arm(7)+grip(2)+pivot(7) = 23；ee = L_ee(6)+R_ee(6)+grip(2)+pivot(7) = 21
class ProprioForward(nn.Module):          # action-expert 的辅助头（单模型内，一次前向）
    def __init__(self, dp=43, da=23, h=256):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(dp + da, h), nn.SiLU(),
                                 nn.Linear(h, h), nn.SiLU(),
                                 nn.Linear(h, dp))
    def forward(self, p_t, a_t):
        return self.net(torch.cat([p_t, a_t], -1))

# 标称残差按维/按相位白化；小样本用对角近似，避免协方差奇异
Sigma_inv = fit_whitening(demo_residuals, phase)   # phase ∈ {reach, contact, transport}

def surprise(p_t, p_next, a_t, fwd, phase):
    r = p_next - fwd(p_t, a_t)
    return float((r * Sigma_inv[phase] * r).sum())  # e_t（Mahalanobis²）

# 事件签名（无触觉，供 I4/I5/I11 使用）：
#   slip：    gripper 开度朝「闭合」指令反向变化 / 负载致 ee 滞后于指令
#   collision：ee 速度突减，且残差集中在末端 3 维
#   human：   保持段 p 突变而 a 平滑，残差全维扩散、方向随机
```

### 1.4 惊异触发的优雅失败状态机（I11）

```python
class GracefulGuard:
    def __init__(self, tau1, tau2, k=3, cooldown=8):
        self.state, self.cnt, self.cd = "NOMINAL", 0, 0
    def step(self, e_t, progress_stall, human_near):
        if self.cd > 0:
            self.cd -= 1
        if self.state == "NOMINAL":
            self.cnt = self.cnt + 1 if e_t > tau1 else 0
            if self.cnt >= k or progress_stall:
                self.state = "SUSPECT"                 # 不确定：减速、保持，不砸进度
        elif self.state == "SUSPECT":
            if e_t > tau2 or human_near:
                self.state = "RECOVER"                 # 可读恢复：减速→后退→重观测→重抓
            elif e_t < 0.5 * tau1:
                self.state, self.cnt = "NOMINAL", 0
        elif self.state == "RECOVER":
            if recovered(...):
                self.state, self.cd = "NOMINAL", cooldown
            elif timeout(...):
                self.state = "ABORT_SAFE"              # 原地保持，绝不碰已完成摆放
        return self.state

# 不确定度调速（仅在 SUSPECT/RECOVER 生效，避免拖慢标称）
def speed_scale(e_t, ood, alpha=1.0, beta=1.0):
```

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
