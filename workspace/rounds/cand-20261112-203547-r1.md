# 第 2 轮（灵感循环 v2 第 1 轮：「应用落地」×「运动规划」）—— 从「语义重试」下沉到「可执行性契约 EMPC」

> 承接当前 research.md 的 UIP-01~10（竞赛对齐研究）。本轮不是再一次推倒重来，而是垂直补一层：上一轮把选手权限内的最高杠杆锁定为「推理时语义验证 + 排行榜步骤分」。本轮指出它在真实部署中的两个结构性缺口——
> 1. **语义验证在关键路径上**：VLM 每步/每块调用会把 p99 延迟和方差推高，而评测端明确记录延迟波动与动作统计规律性，用于结果可信度判定。
> 2. **语义验证修不了几何**：动作块可能运动学不可行、撞桌面/装置、超关节限位、抖动突变；而 API 的 chunk 在两次 `get_action` 之间是开环执行，没有新观测、没有打断机制。语义说「继续」，不代表这条轨迹「执行得动」。
>
> 因此本轮把「运动规划」从底层黑盒提升为 API 内部的一等公民，把「应用落地」从「模型更强」改写为「在截止时间内交付可执行、可恢复、可审计的动作块」。一句话：**语义判断回答「该不该做」，几何契约回答「做不做得到、来不来得及、错了怎么退」。**

---

## 0. 直觉：两个灵感词其实在说同一件事

### 0.1 「运动规划」的直觉

想象一条被远程策略返回的 6~30 步动作块。它是一串「意图」，不是一条「可执行轨迹」：关节可能在两步之间跳 30 度，末端可能从杯沿穿过去，肘部可能已经贴到桌面。真实机器人不会因为策略「语义正确」就原谅这些几何错误。运动规划在这里不是要再训一个模型，而是做三件确定性的事：

- **证书**：在执行前判断这条块是否在可行域内，给出最小安全裕度；
- **修复**：若不可行，把块投影到最近的可行轨迹，而不是整段丢弃；
- **兜底**：若修复失败，输出安全保持/后退，并显式标记 degraded。

这三件事都很便宜（毫秒级到几十毫秒），且可解释、可审计。

### 0.2 「应用落地」的直觉

比赛不是离线 benchmark。选手只在远端暴露一个 `observation→action` API，评测系统用 N 台真机随机顺序调用；每个端口要独立，延迟均值/波动与动作统计规律性会被记录。真正决定名次的，不只是「模型在理想图上多准」，而是：

- 每步是否在预算内返回；
- 延迟是否稳定（不能这一步 15 ms、下一步 200 ms）；
- 动作是否平滑、是否符合统计规律（不能被判为异常跳变）；
- 失败时能否保住步骤分、能否恢复；
- 32 个任务、180 秒上限、5 类泛化轴下是否都能跑。

所以「应用落地」不是一句商业口号，而是一个**运行时契约**：任何计算都必须在截止时间内完成，任何不能按时完成的计算都必须被降级，而不是拖垮整步。

### 0.3 本轮的核心直觉

把语义验证从「每一步的法官」降级为「执行窗口里的后台审计员」；把运动规划从「底层控制器的事」升级为「API 返回动作前的可执行性契约」。于是形成一条与上一轮不同的分工：

```text
同步关键路径（必须 ≤ D）:  VLA 提议 → 几何证书 → 随时修复/兜底 → 返回动作块
异步执行窗口（不阻塞返回）: 语义审计 → 下一块边界合并 → 修正信念/子目标
```

这条分工同时命中两个灵感词：运动规划提供**低延迟、确定性的可行性证据**；应用落地要求**把昂贵语义计算移出关键路径**。

## 2. 严谨定义：把「可执行性契约」写成可检验的命题

### 2.1 动作块与开环执行

设第 \(t\) 次调用时观测为 \(o_t\)，语言为 \(\ell\)。策略返回动作块

\[
A_t=(a_{t,1},\dots,a_{t,H})\in\mathbb{R}^{H\times d},
\]

其中 \(H\) 为返回的 chunk 长度，\(d\) 为动作维度（joint 或 ee）。评测端在两次调用之间顺序执行整个块，期间不提供新观测。因此下一次观测对应时刻 \(t+H\)，而不是 \(t+1\)。

**关键推论**：块内误差会累积。若单步跟踪误差满足

\[
e_{k+1}\le (L+1)e_k+w_k,\qquad w_k\le w_{\max},
\]

则块末误差上界为

\[
e_H\le \frac{(L+1)^H-1}{L}\,w_{\max}.
\]

它与 \(H\) 近似指数相关。给定安全裕度 \(m\)，可反解出「几何上还可信」的最大块长

\[
H_{\text{safe}}\le \frac{\log\!\left(1+\frac{Lm}{w_{\max}}\right)}{\log(L+1)}.
\]

这就是「运动规划 + 应用落地」的第一个硬约束：**块越长，语义上越省调用，几何上越危险**。本轮不拍脑袋选 \(H\)，而是把 \(H\) 作为契约的一部分，用离线标定的误差分位数来选。

### 2.2 可行域与证书

令 \(q_t\) 为关节状态，\(\mathcal{C}_t\) 为第 \(t\) 次调用时的可执行集合。一个动作块 \(A\) 可行，当且仅当存在关节轨迹 \(q_{1:H}\) 满足：

- 关节限位：\(q_{\min}+\delta_q\le q_k\le q_{\max}-\delta_q\)；
- 速度/加速度：\(|\dot q_k|\le \dot q_{\max}\)，\(|\ddot q_k|\le \ddot q_{\max}\)；
- 自碰撞、桌面/装置/物体碰撞：\(d_{\text{col}}(q_k)\ge \epsilon_{\text{col}}\)；
- 可操作度/奇异：\(\sigma_{\min}(J(q_k))\ge \epsilon_{\text{manip}}\)；
- IK 残差：\(\|\log(T_{\text{des},k}^{-1}f(q_k))\| \le \epsilon_{\text{ik}}\)。

定义**可执行性证书**为一个三元组

\[
\operatorname{Cert}(A;o_t)=\big(v,\,m,\,\rho\big),
\]

其中 \(v\in\{0,1\}\) 是可行性判定，\(m\) 是最小归一化安全裕度（越大越安全），\(\rho\) 是修复相对原块的偏离量。证书不是「成功率预测」，而是**执行前的充分条件检查**：它只能保证「不违反被建模的几何约束」，不能保证「任务语义成功」。这一点必须写进接口，避免把几何安全误当成任务成功。

### 2.3 可执行性修复算子

若 \(A\notin\mathcal{C}_t\)，定义修复算子

\[
\Pi_{\mathcal{C}_t}(A)
=\arg\min_{A'\in\mathcal{C}_t}
\|A'-A\|_W^2+\lambda\,S(A'),
\]

其中 \(S(A')\) 是平滑/加加速度惩罚。\(\Pi\) 的语义是：**尽量保留 VLA 的意图，只改到「能执行」**。如果修复后的偏离 \(\rho\) 很大，说明原意图可能本身有问题，应触发语义审计或重规划，而不是继续硬修。

**随时性（anytime）**：\(\Pi\) 在预算内返回当前最优可行解；预算耗尽仍未可行，则返回安全兜底（保持/后退），并标记 `degraded`。这样，“算不完”不会变成“返回坏动作”。

### 2.4 截止时间契约

设每次 `get_action` 的预算为 \(D\)（例如 60 ms）。一个部署契约是四元组

\[
\mathcal{K}=(H,\,k,\,D,\,\text{fallback}),
\]

其中 \(k\le H\) 是本次承诺执行的步数，\(D\) 是硬截止时间，fallback 是超时/不可行时的安全动作。契约要求：

\[
\Pr[\text{latency}\le D]\ge 1-\delta_{\text{lat}},
\qquad
\Pr[\operatorname{Cert}=1]\ge 1-\delta_{\text{geo}},
\]

且 fallback 本身必须满足安全约束。注意：这两个概率不是「任务成功率」，而是「运行时契约的守约率」。

### 2.5 异步语义审计

语义验证器 \(V(o_t,\ell,g)\) 仍然有用，但它被移到执行窗口：

1. 第 \(t\) 次调用返回已修复的动作块，**不等待** \(V\)；
2. 在评测端执行该块的 \(H\) 步期间，后台运行 \(V\)；
3. 第 \(t+H\) 次调用时，如果后台结果已就绪，就合并到信念/子目标；未就绪则跳过，绝不阻塞。

形式化地，语义修正有一个不超过一个块周期的滞后 \(L_{\text{sem}}\le H\)。这把语义验证的延迟从关键路径移到了「执行窗口」的闲置算力上，代价是修正晚一个块生效。

### 2.6 目标函数：为什么不能只最大化成功率

官方综合排名同时看平均成功率与步骤分，且延迟/动作异常影响可信度。定义部署效用

\[
U=\alpha\cdot\text{Success}+\beta\cdot\text{StepScore}
-\gamma\cdot\mathbb{1}[\text{p99}>D]
-\delta\cdot\operatorname{Var}(\text{latency})
-\zeta\cdot\operatorname{Jerk}(A).
\]

在官方权重未知时，采用**字典序安全的优化**：

1. 先保证不触发可信度红线（p99 ≤ D、动作不异常）；
2. 再在同等预算下最大化成功率与步骤分的帕累托前沿；
3. 最后才追求平均成功率的最后一个百分点。

这解释了一个反直觉现象：**一个成功率略低但碰撞更少、能保住步骤分的策略，可能比一个成功率略高但动作狂躁的策略排名更稳**。

### 2.7 三个可检验命题

**命题 1（块长-风险）**：在 2.1 的误差增长模型下，固定安全裕度 \(m\) 时，可行块长 \(H\) 的上界随 \(w_{\max}\) 增大而下降；因此「更大 chunk」不是免费的，必须用标定误差反选。

**命题 2（契约守约）**：若同步关键路径各阶段 p99 延迟分别为 \(D_1,\dots,D_s\)，且 \(\sum_i D_i\le D\)，则端到端 p99 不超过 \(D\)（按阶段串行、各自 p99 校准）。修复算子不增加被建模约束的违反量；但它可能增加语义偏离 \(\rho\)，故必须把 \(\rho\) 作为触发语义审计的信号。

**命题 3（步骤分）**：若步骤分对「进度」和「安全」单调，则把一个不可行块替换为可行的部分完成轨迹，可以在成功率不变的情况下提高步骤分。这正是本轮代理实验要检验的机制。

## 5. 旗舰点深潜：EMPC（Executable Motion-Planning Contract）

### 5.1 四个部件

```text
             ┌──────────────── 同步关键路径（≤ D） ────────────────┐
o_t, ℓ  ──►  │ VLA 提议 A_t ──► 几何证书 ──► 随时修复 Π ──► 兜底  │ ──► A'_t
             └──────────────────────────────────────────────────────┘
                                      │
                                      ├── 在执行窗口后台：语义审计 V(o_t,ℓ,g)
                                      └── 下一块边界：合并审计结果、更新子目标
```

1. **MP-Compiler（运动基元编译）**：把 VLA 输出统一成关节轨迹。若 VLA 给 ee 位姿，用带演示姿态先验的 IK 转 joint；若给 joint，直接检查限位/速度/加速度。输出带时间参数化的轨迹，而不是裸点列。
2. **Certificate（几何证书）**：按 2.2 检查限位、速度/加速度、自碰撞、桌面/装置碰撞、可操作度、IK 残差。碰撞世界由三部分组成：固定桌面平面、任务装置先验（从演示提取的保守包围盒）、在线可移动物体（双目/颜色/轮廓 + 保守膨胀）。透明/反光物体不硬求深度，直接用演示先验膨胀。
3. **Anytime Repair（随时修复）**：在预算内做局部轨迹优化/采样修复；先修最危险的约束（碰撞 > 限位 > 平滑），再修偏差。修复失败就用兜底：保持、沿障碍法向后退、或回到上一个已证书块的最后安全姿态。所有 fallback 都限速、限幅、有最大重试。
4. **Async Semantic Audit（异步语义审计）**：VLM 只在后台运行；用「歧义分数」或固定周期触发；最多一个 pending，结果晚一个块生效。若后台队列积压或超时，直接丢弃，不影响同步路径。

### 5.2 关键算法（伪代码）

```python
class EMPCPolicy:
    def __init__(self, vla, compiler, certifier, repair, verifier,
                 H=6, deadline_ms=60, audit_period=2):
        self.vla, self.compiler = vla, compiler
        self.certifier, self.repair = certifier, repair
        self.verifier = verifier
        self.H, self.D = H, deadline_ms
        self.audit_period = audit_period

    def reset(self):
        self.belief = None
        self.pending = None
        self.t = 0

    def get_action(self, obs):
        t0 = now_ms()

        # 1) 合并上一块执行窗口里算好的语义审计（绝不阻塞）
        if self.pending is not None and self.pending.done():
            self.belief = self._merge(self.belief, self.pending.result())
        self.pending = None

        # 2) VLA 提议（可在上一块执行期间预取，进一步降延迟）
        A = self.vla.propose(obs, self.belief)

        # 3) 同步几何层：证书 + 随时修复，硬截止 D
        traj = self.compiler.to_joint_trajectory(A, obs)
        budget = deadline_budget(self.D, t0)
        traj, cert = self.repair.anytime(traj, obs, budget)

        if not cert.feasible:
            traj = self._fallback(obs, cert)   # hold / backoff / last safe

        # 4) 启动后台语义审计（不等待）
        if self._should_audit(obs, cert, t0):
            self.pending = self.verifier.submit(obs, self.belief)

        # 5) 返回；响应时间由 D 约束
        return self.compiler.to_action_chunk(traj, self.H)
```

**三重护栏**：硬截止 \(D\) 限制同步路径；`anytime` 保证算不完也有可行解；`fallback` 保证连修复都失败时仍不返回坏动作。

### 5.3 与已有路线的差异

- **对比开环 chunk（ACT/pi0 式）**：不假设块内动作天然可执行；返回前做几何证书与修复。
- **对比 UIP-01 同步 VLM 重试**：语义计算移出关键路径；几何层用确定性证据先兜底，语义只做慢速审计。
- **对比通用 CBF/安全层**：不做 30Hz 广域网 CBF；只做**块级**证书与修复，适配远端 API 的低频观测。
- **对比世界模型 MPC（UIP-04）**：不依赖学习世界模型的保真度；几何层可解释、可标定、毫秒级；世界模型只做离线预演。
- **对比 UIP-08 静态延迟工程**：不是「压平均延迟」，而是「用截止时间契约约束最坏延迟」，并把昂贵计算搬到执行窗口。

### 5.4 可证伪的预测

若 EMPC 有效，应观察到：

1. 在相同 VLA 与相同任务分布下，碰撞率显著下降，步骤分上升；
2. 同步路径 p99 不超过 \(D\)，延迟方差显著低于同步 VLM；
3. 仅靠 EMPC 不能修复语义错误，成功率提升有限；加上异步语义审计后成功率再上一台阶；
4. 当标定误差/深度误差增大时，证书的假阳性（错判为可行）上升，收益下降；这是方案失效的边界。

## 1. 旗舰 UIP-11：EMPC 机制

### 1.1 运行时数据流

```text
同步关键路径（必须 ≤ D）:
  o_t, ℓ ──► VLA 提议 A_t ──► MP-Compiler ──► 几何证书 ──► 随时修复 Π ──► 兜底
                                                                          │
                                                                          ▼
                                                                       A'_t 返回

异步执行窗口（不阻塞返回）:
  评测端执行 A'_t 的 H 步 ──► 后台 VLM 审计 V(o_t,ℓ,g) ──► 下一块边界合并
```

### 1.2 四个部件

**MP-Compiler（运动基元编译）**
- 若 VLA 输出 ee 位姿：用带演示姿态先验的 IK 转成 joint 轨迹；先验来自同任务成功演示的关键帧关节角，优先保持「演示过的肘部构型」。
- 若 VLA 输出 joint：直接检查限位、速度、加速度。
- 输出带时间参数化的轨迹，而不是裸点列；后续证书与修复都在轨迹上做。

**Certificate（几何证书）**
- 约束：关节限位、速度/加速度、自碰撞、桌面/装置/物体碰撞、可操作度、IK 残差。
- 碰撞世界三层：
  1. 固定桌面平面（标定）；
  2. 任务装置先验（从演示提取的保守包围盒/胶囊，随任务坐标系重定位）；
  3. 在线可移动物体（双目视差/颜色/轮廓 + 保守膨胀；透明/反光物体直接用演示先验膨胀，不硬求深度）。
- 输出 \((v,m,\rho)\)：可行性、最小归一化裕度、修复偏离量。

**Anytime Repair（随时修复）**
- 预算内做局部轨迹优化/采样修复；优先级：碰撞 > 限位/速度 > 平滑 > 偏离。
- 修复失败 → fallback：保持、沿最近障碍法向后退、回到上一个已证书块的最后安全姿态。
- 所有 fallback 限速、限幅、有最大重试次数；连续 degraded 触发恢复/重规划。

**Async Semantic Audit（异步语义审计）**
- VLM 只做后台审计：按固定周期（如每 2 块）或歧义分数触发；最多一个 pending。
- 结果晚一个块生效；未就绪就跳过，绝不阻塞 `get_action`。
- 合并方式：更新子目标信念/阶段；若审计与几何证书冲突（几何可行但语义说目标错），优先触发重感知/重规划，而不是继续执行。

### 1.3 截止时间契约

\[
\mathcal{K}=(H,k,D,\text{fallback}),\qquad
\Pr[\text{latency}\le D]\ge 1-\delta_{\text{lat}},\qquad
\Pr[\operatorname{Cert}=1]\ge 1-\delta_{\text{geo}}.
\]

- \(H\)：返回块长；
- \(k\le H\)：本次承诺执行步数；
- \(D\)：硬截止；
- fallback：超时/不可行时的安全动作。

**三条硬规则**：
1. 同步路径只做几何层；语义层一律异步。
2. 修复是 anytime 的：预算耗尽返回当前最优可行解，不返回「算到一半的坏块」。
3. 任何不确定都降级为保守动作，而不是赌一把。

### 1.4 与 UIP-01~10 的关系

| 现有点 | 本轮处理 |
|---|---|
| UIP-01 同步语义验证 | 降级为 UIP-14 异步审计；保留其子目标/置信度思想 |
| UIP-02 步骤分安全网 | 由 UIP-11 的安全部分完成 + UIP-13 的相位进度补足 |
| UIP-04 世界模型 MPC | 移出关键路径，只做离线/异步候选筛选 |
| UIP-07 回放 harness | 扩展指标：成功率 + 步骤分 + 碰撞率 + 修复率 + 延迟 |
| UIP-08 延迟工程 | 从「压平均」升级为「硬截止 + 异步队列」 |
| UIP-10 控制空间仲裁 | 改为按证书/可操作度动态选 joint/ee（UIP-15） |

## 2. 关键算法（EMPC 伪代码）

```python
class EMPCPolicy:
    def __init__(self, vla, compiler, certifier, repair, verifier,
                 H=6, deadline_ms=60, audit_period=2):
        self.vla, self.compiler = vla, compiler
        self.certifier, self.repair = certifier, repair
        self.verifier = verifier
        self.H, self.D = H, deadline_ms
        self.audit_period = audit_period

    def reset(self):
        self.belief = None
        self.pending = None
        self.t = 0

    def get_action(self, obs):
        t0 = now_ms()

        # 1) 合并上一块执行窗口里算好的语义审计（绝不阻塞）
        if self.pending is not None and self.pending.done():
            self.belief = self._merge(self.belief, self.pending.result())
        self.pending = None

        # 2) VLA 提议；可在上一块执行期间预取
        A = self.vla.propose(obs, self.belief)

        # 3) 同步几何层：证书 + 随时修复，硬截止 D
        traj = self.compiler.to_joint_trajectory(A, obs)
        budget = deadline_budget(self.D, t0)
        traj, cert = self.repair.anytime(traj, obs, budget)

        if not cert.feasible:
            traj = self._fallback(obs, cert)   # hold / backoff / last safe

        # 4) 后台语义审计（不等待）
        if self._should_audit(obs, cert, t0):
            self.pending = self.verifier.submit(obs, self.belief)

        # 5) 返回；响应时间由 D 约束
        return self.compiler.to_action_chunk(traj, self.H)

    def _should_audit(self, obs, cert, t0):
        # 周期兜底 + 歧义/修复偏离触发；任一满足即提交
        return (self.t % self.audit_period == 0) or (cert.rho > RHO_GATE)

    def _fallback(self, obs, cert):
        # 优先级：保持 > 远离最近障碍 > 回到上一安全姿态
        return self.safe_hold(obs)
```

## 3. 合成代理实验（已运行，非榜单证据）

### 3.1 目的与声明

**目的**：隔离一个问题——当动作块同时存在「语义错」和「几何不可行」时，几何契约、同步语义验证、异步语义审计三者的收益与延迟代价如何排序？

**声明**：这是一个纯 Python 平面 2 连杆臂的合成机制检验，不是 32 任务真机结果。绝对数值无意义；有意义的是**排序与权衡**。代码与原始结果：
- `exp/empc_sim.py`
- `exp/empc_results.json`

### 3.2 生成模型（显式声明，未拟合真实数据）

- 平面 2 连杆臂，关节空间动作块 \(H=6\)，块内无反馈；
- 每回合最多 10 个块；
- 动作块由 VLA 对「信念目标」做 IK 插值并加噪声/偶发 jerk；
- 38% 的回合存在语义/感知偏移（错误目标），块会稳定地走向错误位置；
- 障碍物为圆形，部分块会碰撞或超限；
- 同步 VLM：TPR=0.78，FPR=0.10，成本 120 ms；
- EMPC：几何修复 + 圆形障碍绕行 + 安全兜底，预算按 60 ms 截止时间分配；
- 异步 VLM：结果晚一个块生效；周期版每 2 块提交一次，歧义版按与语义错误相关的歧义分数提交；
- 指标：成功率、步骤分类分数（0–100，进度+安全）、碰撞率、p95 延迟、截止超时率、后台计算量。

### 3.3 结果（N=1800）

| 策略 | 成功率 | 步骤分 | 碰撞率 | 延迟均值 ms | p95 ms | 超时率 | 后台 ms/回合 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 开环 chunk | 28.5% | 42.8 | 70.4% | 15.0 | 15.0 | 0.0% | 0.0 |
| 同步 VLM（UIP-01 式） | 38.5% | 51.2 | 61.5% | 135.0 | 135.0 | 100.0% | 0.0 |
| EMPC（纯几何） | 35.3% | 52.3 | 45.2% | 59.0 | 59.0 | 0.0% | 0.0 |
| 同步 VLM + EMPC（歧义触发） | 50.9% | 58.3 | 41.8% | 91.8 | 179.0 | 57.6% | 0.0 |
| 异步 VLM + EMPC（歧义触发） | 49.3% | 56.8 | 43.6% | 59.0 | 59.0 | 0.0% | 131.3 |
| 异步 VLM + EMPC（周期触发） | 50.7% | 57.9 | 42.8% | 59.0 | 59.0 | 0.0% | 221.0 |

### 3.4 解读

1. **纯几何 EMPC 把碰撞率从 70.4% 降到 45.2%，步骤分从 42.8 提到 52.3**，但成功率只从 28.5% 到 35.3%——因为语义错误仍在。这验证了「几何修不了语义」。
2. **同步 VLM 成功率更高（38.5%），但 p95 135 ms、100% 超出 60 ms 预算，且碰撞率仍 61.5%**。它把延迟风险换成了语义收益，在真实部署里会触发可信度问题。
3. **同步 VLM + EMPC 成功率最高（50.9%），但 p95 179 ms、57.6% 超时**。这说明「把两个好东西都塞进关键路径」不是可部署方案。
4. **异步 VLM + EMPC 在 p95 59 ms、0% 超时的前提下拿到 49.3% 成功率 / 56.8 步骤分**，保留了同步版约 95% 的收益，把超时全部消除，代价是每回合约 131 ms 的后台算力。
5. **周期触发（每 2 块）几乎追平歧义触发（50.7% vs 49.3%）**，说明「歧义检测器」不是本方案的生死条件；没有可靠的歧义信号时，固定周期后台审计也能工作，只是后台算力更高（221 ms/回合）。

### 3.5 局限

- 平面 2 连杆、圆形障碍、手写生成模型，不能外推到 G1 的 7-DoF 双臂、透明物体、桌面装置；
- 语义错误与「歧义分数」的相关性是人为设定的，真实中需要视觉/几何 novelty 校准；
- 修复器是简化版坐标下降 + 圆形绕行，不是 cuRobo/MPC 级轨迹优化；
- 绝对成功率低于真实比赛（真实 VLA 基线不同），但排序与延迟/收益权衡是机制层面的证据。

**最大风险（一句话）**：几何证书若建立在错误标定或不可靠的碰撞世界上，会把「不可执行」误判为「可执行」，在低延迟的假象下稳定撞向错误目标；因此风险核心是**证书可信度**，不是算力。

**风险分解与缓解**：

| 风险 | 表现 | 缓解 |
|---|---|---|
| 标定误差（URDF/TCP/手眼） | 证书假阳性、末端偏几毫米到几厘米 | 用演示做 held-out 标定；分位数膨胀；每端口在线残差监控 |
| 无 depth / 透明反光 | 碰撞世界缺失或错误 | 演示先验包围盒 + 保守膨胀；不硬求深度；透明物体单独降级 |
| 修复改变语义 | 轨迹可行但偏离原意图 | 用修复偏离 \(\rho\) 触发异步审计/重规划；\(\rho\) 超阈值不修复，直接兜底 |
| 异步审计过时 | 用上一块的结果修正当前块 | 限制最多一个 pending；陈旧结果按置信度降权/丢弃 |
| 计划器抖动 | 几何层本身超时 | 固定迭代上限 + anytime 返回 + 预计算碰撞世界 + 端口预热 |
| 单模型合规 | 几何层被误认为第二个策略 | 几何层是确定性/标定层，不加载第二个学习策略；若用学习碰撞预测，需单独合规审查 |

**Kill criteria**：若 E011 假阳性 >10%，或 E012 p99 超时 >1%，或步骤分提升 <5 分，则停止 EMPC 的「修复」路线，退化为「几何过滤 + 安全保持」的最小版本，把资源移回 UIP-02/UIP-01 的轻量组合。

---

## 7. 本轮结论

- 「运动规划」在本赛事里不是底层控制器的专利，而是 API 返回动作前的**可执行性契约**：证书、修复、兜底。
- 「应用落地」的关键不是把最强模型塞进同步路径，而是**把昂贵语义计算移出关键路径**，用几何层守死延迟与安全。
- 合成代理实验支持这一分工：纯几何 EMPC 显著降碰撞/提步骤分；异步语义审计在 p95 59 ms、0% 超时的前提下拿到接近同步组合的成功率。
- 最大的不确定性不是算法，而是**几何证书在真实 G1 上的可信度**；因此下一轮应优先做标定与离线回放假阳性评估，而不是继续堆模块。
