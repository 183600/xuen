# 第 8 轮 · RUBICON：世界模型当裁判，闭环控制当教练，通用平台当考场

> 检索/复核日期：**2026-10-26（UTC）**。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、5 类泛化场景、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「通用机器人平台」「闭环控制」「世界模型」。我先做一件不讨喜但必须做的事：**纠正一个前提**——你在页面上看到的“榜首 29.7%、不到 30%”并不是真实榜单，而是 `gen_leaderboard.py` 生成的占位数据；真实排行榜仍写着「即将发布」。因此本轮不能真的去“分析榜首方案”，只能分析**占位名单所代表的模型家族**的公开做法，并用外部真机基准（RoboChallenge Table30）给出更可信的“通才天花板”。在这个基础上，我的主判断是：**UniBot 当前最大的可改进量不在“再训一个更大的 VLA”，而在“给任意一个强通才底座加一层评分图条件化的世界模型裁判”：它在推理时做 chunk 级动作条件验证、步骤级进度/撤销检测、分数感知的重试分配，并把稀缺的真机调试槽变成可校准的离线评估器。** 这比继续堆数据/堆参数更贴近评分结构，也更适合单模型 + 远程 API 的约束。

## 0. 本轮先核实：七个事实，其中一个推翻了用户前提

### 0.1 “榜首 29.7%”是占位数据，不是真实榜单

我通过 `r.jina.ai` 绕过高风险拦截，抓到了 `leaderboard.html` 的渲染快照与 `leaderboard_data.json`（[S2][S3]）：

- 页面确实显示 8 个模型：MolmoAct/DexHacker 29.7%、WALLOSS/Generalist Robotics 28.5%、DreamZero/World Model Lab 27.9%、Spirit/VLAGO 25.9%、DM/Embodied AI Institute 23.5%、PI/RoboReasoner 22.8%、GigaBrain/xembody 22.6%、GR00T/Humanoid Dynamics 20.5%。
- 但 JSON 第一行是 `"generated_from": "gen_leaderboard.py"`，256 条 task_metrics 是脚本生成的；点进任何详情页，32 个任务的视频全部写着「测试视频占位，后续可替换为真实视频文件」（[S4]）。
- 榜单页本身仍显示「即将发布 / Coming Soon」，运行记录页同样是「即将发布」。

**结论：这 8 行数字只能当“UI 演示/难度先验”，不能用来判断谁强谁弱，更不能用来推断轴级瓶颈。** 你看到的“榜首不到 30%”恰好是占位数据的第一行 29.7%，不是真实比赛结果。真实榜单发布后，必须重跑本轮的所有排名假设。

数据结构仍是 LeRobot v3：四路相机（`head_stereo_left/right`、`wrist_left/right`）、双臂关节/EE 位姿、夹爪、lower body、base/torso 两套坐标；`action.left_arm`、`action.right_arm`、`action.left_gripper`、`action.right_gripper`、`action.lower_body`、`action.pivot` 等。每任务 5 条英文复述（第 7 轮已核实，本轮沿用）。

### 0.3 官方基座 UnifoLM-WLA-1.0 已开源，且能在单张 24GB 卡上微调

这是本轮最重要的“平台事实”（[S12][S13][S14][S15]）：

- **6B 参数**，基于 UnifoLM-ER-Flow 多模态 backbone + MMDiT action expert；训练约 **2,500 小时**真机数据；单模型覆盖 **64 个任务**（54 桌面 + 10 全身）；Apache-2.0；checkpoint 约 12.5GB。
- 官方明确写了「以交互为中心的世界建模」：用光流提取未来动态区域，VQ-VAE 离散化，再让 VLM 在当前图像 + 任务/动作条件下预测**未来动态区域 token**。这不是“重建整个世界”，而是“预测交互会改变哪些区域”。（[S14]）
- 2026-09-28 发布 `UnifoLM-WLA-1.0-Base` 和微调代码；官方训练指南写明：**冻结 VLM backbone，只训 action expert（DiT）和 robot-state projector；默认配置面向单张 24GB GPU；支持 LoRA。**（[S15]）
- 配置里 action_dim=54、action_horizon=30、DiT-L、state_dim=120，正好对应 G1 Dex1 的双臂 + 夹爪 + 下肢动作。
- 官方**没有公布逐任务成功率**；第三方评测也指出“有权重、有视频、没有 success rate”。（[S32]）

这给了一个非常现实的路线：**不要从零训 6B VLA，直接用官方基座 + 官方数据微调 action expert；把研究火力放在它已有的“动态区域世界模型”之上，加评分图条件和闭环裁判头。** 这比第 7 轮“GPR-VLA 从零/大改”务实得多。

### 0.4 提交接口 v2 没有变化，仍然允许我们做观测裁剪、时序堆叠、图像缩放和 chunk 控制

`unibot_submission` 仓库最近一次提交仍是 2026-08-21 的 v2（[S8]）。关键约束/自由度：

- 观测：4 路 RGB 480×640、双臂关节/EE 位姿（base 系）、夹爪、下半身、`observation.language` 单字符串（episode 内不变）。
- `obs_delta_indices`：我们自己声明传哪些键、每键堆叠几帧；`image_resize` 自定；`action_chunk_size` 自定；动作空间 joint 或 ee 互斥。
- `reset()` 每 episode 一次；token 双处校验；评测端按 N 台机器人开 N 个连续端口（8765 起），每个端口独立完成整个交互。
- 评测端执行 action chunk；我们不在低层控制器里，但可以在 chunk 边界做闭环。

**这意味着：世界模型裁判完全可以在服务端跑，不需要改机器人底层；观测裁剪、锚点渲染、chunk 级验证、重规划都在接口允许范围内。** 单模型边界（一个 policy class 内是否允许辅助头/辅助模型）官方没有形式化定义，本轮按“一个 checkpoint、多个头、全部披露”设计，见 §9。

### 0.5 外部真机基准给出了更可信的“通才天花板”：约 37%–43%

UniBot 真实榜单没发布，但 RoboChallenge Table30 是可比的真实桌面对外基准（[S16][S17][S18]）：

- **Table30 v1（任务级/专家）**：DM0 62.0%、Era0 64.3%、GigaBrain-0.1 51.67%、Spirit-v1.5 51.0%、π0.5 42.67%。
- **Table30 v1（通才/单模型）**：Lira_generalist 45.0%、Atlas_generalist 39.67%、DM0_generalist 37.33%、VLO 25.67%、π0.5_generalist 17.67%。
- **Table30 v2（更难、通才协议）**：LoopWAM 43.33%、VLA-DM0.5 40.67%、ambase 31.67%、my16 30.67%。

也就是说：**真实桌面上，专家模型可以到 62%–64%，但单模型通才的天花板只有 37%–43%；“通才税”约 20–25 个百分点。** UniBot 是 32 任务 × 5 泛化轴的通才赛道，真实榜首即使低于 30% 也不奇怪；但这不是“模型太笨”，而是“通才在长程/接触/ OOD 上丢的可靠性”。这比占位榜单的 29.7% 更有信息量。

### 0.6 世界模型/闭环控制的最新证据：验证器比“更大的策略”更便宜，也更直接

本轮重点检索了 2026 年的执行时验证与闭环世界模型（[S20]–[S25]）：

- **CheckVLA**（2026-07）：冻结的 action-conditioned world model 在执行时预测“剩余动作会导致什么”，用 conformal 阈值决定何时干预；RoboCasa365 上 36.1% vs 周期重规划 27.6%（**+8.5pp**）；在 5% 误报率下，动作条件把及时召回从 48.6% 提到 77.9%。
- **VeriVLA**（2026-10）：用 JEPA 式 latent world model 对候选 action chunk 排序；三个真机任务平均完成分 **50.8%→65.5%（+14.7pp）**；每次触发验证约 **326ms**（单张 4090）；RoboTwin 干净 66.4→73.6、随机 62.8→69.6。
- **SV-VLA**（2026-04）：重 VLA 低频出 chunk，轻量 verifier 持续监控，只在必要时重规划；把“开环长程规划 + 闭环在线验证”拆开。
- **VLA-Corrector**（2026-09）：用可观测历史学习 stage-aware verifier（approach/alignment/grasp/transport/placement），检测异常后用 stage-conditioned recovery prompt 让同一个冻结 VLA 恢复；不需要特权状态。
- **PiL-World / ProWorld**（2026-06/10）：chunk-wise 世界模型做 policy-in-the-loop 评估；PiL-World 把“世界模型估的成功率 vs 真机成功率”误差从 63.2% 降到 12.0%；ProWorld 做到 Pearson 0.95 / Spearman 0.94。
- **LingBot-VA / Long-WAM / DreamZero**：世界-动作模型（WAM）作为策略确实强——LingBot-VA RoboTwin 92.9%/91.6%，Long-WAM 在 G1 动态叠杯 95%、每 chunk 107.4ms，DreamZero 14B 7Hz、零样本泛化 2×。但它们要么训练极贵（Long-WAM 预训练约 30,720 GPU-hours），要么推理很重；而且它们仍然主要在“预测未来/生成动作”，**不直接知道 UniBot 的 32 张评分步骤图和 180 秒预算**。

**结论：世界模型当“策略”是重资本路线；当“裁判/评估器”是轻资本、与评分结构直接对齐的路线。** 我们选后者作为主押注，把前者作为可选底座。

### 0.7 评分结构仍是第一性依据：终局步是闸门，放置类是大头

第 7 轮已抓全 32 个 `tasks_v2/<slug>/info.json`，本轮抽检 T27 与 T10 未变（[S10][S11]）：

- T27 StackBowls：30（碗1放中间）/ 30（碗2叠碗1）/ 40（碗3叠碗2）。
- T10 PlugCharger：30（抓插排）/ 30（抓插头）/ 40（插入）。
- 32 任务终局步骤合计 1275/3200 = **39.8%**；放置/插入/堆叠/闭合类步骤约 1910/3200 = **59.7%**；成功=所有步骤完成，所以终局步同时是“成功闸门”和“最大单项分”。

这决定了：**任何能提高终局步可靠性、并能检测“做完又被撤销”的机制，都同时赚成功率、步骤分和跨五轴的杠杆。** 第 7 轮的 PILOT 方向仍然成立；本轮只是把“落点 settle 闭环”升级成“全 chunk 的世界模型裁判 + 评分图进度”。

## 1. 三个灵感词，各自钉到官方/外部事实上

### 1.1 通用机器人平台：不是“硬件”，而是“一个模型 + 一套评分图 + 一个评测集群”

UniBot 的“通用”有三层：

1. **硬件通用**：同一台 G1 + Dex1 跑 32 个任务；不是每个任务一台专用机器人。
2. **模型通用**：单模型覆盖 32 任务；不能靠每任务 LoRA/专家。
3. **评测通用**：同一套 API、同一套评分步骤、五个泛化轴；远程真机集群。

因此，平台上的最优策略不是“把某个任务做到 90%”，而是**把“通才的可靠性”整体抬上去**。外部证据说得很清楚：专家 62% vs 通才 37%，差距不在语义理解，而在执行可靠性。**平台视角的创新点，应该是一个“跨任务共享的裁判层”，而不是又一个任务专用技巧。**

官方基座 UnifoLM-WLA-1.0 本身就是“平台原生”的：6B、64 任务、2,500 小时、交互中心世界模型、Apache-2.0、24GB 可微调。它把“通用平台”的底座问题解决到了“可用”程度；剩下的问题是：**通用底座在具体评测分布上不够可靠，而且不知道自己哪一步做错了。** 这正是裁判层的空间。

### 1.2 闭环控制：不是“再来一次 PID”，而是四个时间尺度的闭环

UniBot 的执行接口是 chunk 级的：`get_action` 返回一段动作，评测端按顺序执行，直到下一次调用。这天然是“开环 chunk 执行”。误差会在 chunk 内传播，等下一次观测回来时，可能已经晚了。我们需要四个时间尺度：

| 时间尺度 | 频率 | 闭环内容 | 现有方案 | 我们的增量 |
|---|---|---|---|---|
| 底层关节 | 30Hz | 关节/EE 跟踪、夹爪开合 | 评测端/机器人底层 | 不碰 |
| Chunk 级 | 0.5–1s | 动作条件预测 vs 实际观测；风险触发；后缀重写 | CheckVLA / SV-VLA / VeriVLA | 用官方基座的动态区域世界模型 + 评分图条件 |
| 步骤级 | 2–10s | 步骤完成/撤销检测；重试/重抓/回退 | SSG 规则 + VLA-Corrector | 学习式 rubric 进度头 + 分数感知重试 |
| Episode 级 | 180s | 剩余分数估计；继续/放弃；发布门 | 人工调试槽 | Latent trajectory evaluator + 真机校准 |

关键点：**chunk 级闭环不需要生成完整未来视频**。只需要预测“这段动作会导致哪些动态区域/位姿变化”，再和实际观测比。官方 ER-Flow 已经在做动态区域预测，这让我们不必从零训一个视频世界模型。

### 1.3 世界模型：当裁判，不当策略；当评分模拟器，不当渲染器

世界模型有三种用法：

1. **当策略**（DreamZero / LingBot-VA / Long-WAM）：预测未来 + 反解动作；强，但重，且不以评分图为条件。
2. **当验证器**（CheckVLA / VeriVLA / SV-VLA）：预测动作后果，和实际比，决定是否重规划；轻，直接提升闭环可靠性。
3. **当评估器**（PiL-World / ProWorld）：policy-in-the-loop 估计成功率；把真机试错变成离线筛选。

UniBot 的特殊性在于：**评分步骤和权重是公开的**。所以我们可以做第三种世界模型的一个变体：**Rubric-Conditioned World Model（RC-WM）**——不只预测“未来长什么样”，还预测“第 i 步完成概率、剩余步骤分、成功率”。这把世界模型从“视觉预测器”变成“评分状态估计器”，直接对齐排行榜的两个指标。

这也是本轮最核心的 novelty：**公开评分图 × 动作条件世界模型 × 分数感知闭环控制**。现有工作分别有“世界模型验证”“阶段恢复”“世界模型评估”，但没有人把官方评分图作为世界模型的条件和输出结构，并用它来做重试预算分配。

## 2. 榜单头部方案与瓶颈：真实差距是“通才税”，不是“语义不懂”

### 2.1 占位头部的八个模型家族（注意：UniBot 数字是占位）

| 占位排名 | 模型家族 | 公开做法/强项 | 对 UniBot 的潜在瓶颈 |
|---|---|---|---|
| 1 | MolmoAct2 | Action Reasoning + 3D grounding + 自适应深度；LIBERO 97.2，但真实 MolmoBot 20.6 / MolmoSpace 37.7 | 仿真-真机落差；没有执行时验证；长程/接触任务掉点 |
| 2 | WALL-OSS-0.5 | 4B 跨 embodiment VLA，20+ 本体预训练 | 广而不精；G1 桌面精密操作/力控不足；无评分图意识 |
| 3 | DreamZero | 14B World-Action Model，7Hz 闭环，零样本泛化 2× | 推理/训练极重；仍是“策略”，不知道步骤分；远程 API 成本高 |
| 4 | Spirit-v1.5 | 4B 通才 VLA；Table30 专家 51% | 通才协议下掉点；无运行时纠错 |
| 5 | DM0 | 2B embodied-native VLA；Table30 专家 62.0 / 通才 37.3 | 通才税 ~25pp；无步骤级恢复 |
| 6 | π0.5 | 3B 通才；语义泛化强；Table30 专家 42.67 / 通才 17.67 | 物理精度/长程可靠性弱；开环 chunk |
| 7 | GigaBrain-0 | 世界模型生成数据 + RGBD + 具身 CoT；3.5B；Table30 51.67 | 世界模型主要在离线造数据；推理时不做后果验证；数据重 |
| 8 | GR00T N1.5 | 跨本体通用；G1 兼容 | 桌面精密操作弱；Table30 multi 仅 13.33 |

**必须强调：这些模型家族的做法是公开的，但它们在 UniBot 上的 29.7/28.5/... 是占位脚本生成的，不是真实评测。** 我们只用它们来代表“头部可能长什么样”，不用它们来排名。

### 2.2 真实差距：专家 62% vs 通才 37%，差的是“可靠性”不是“知识”

RoboChallenge Table30 的证据（[S16][S18]）：

```text
专家（每任务微调）:  DM0 62.0, Era0 64.3, GigaBrain-0.1 51.67, Spirit 51.0, π0.5 42.67
通才（单模型全任务）: Lira 45.0, Atlas 39.67, DM0 37.33, VLO 25.67, π0.5 17.67
Table30 v2 通才:      LoopWAM 43.33, VLA-DM0.5 40.67, ambase 31.67
```

同一個 DM0，专家 62.0、通才 37.3，**差 24.7pp**。这不是“模型不认识物体”，而是：

- 多任务共享容量导致每任务精度下降；
- 长程任务误差累积；
- 接触丰富任务（插头、拉链、叠碗、拧盖）对位姿/力控要求高；
- 评测分布有 5 个泛化轴，训练数据主要是名义成功演示；
- 开环 chunk 执行让一次小偏差滚成失败。

**谁能用“一个通才模型”把 37% 抬到 45%–50%，谁就赢。** 这比把某个任务从 80% 做到 90% 更符合赛道定义。

### 2.3 五个瓶颈

| # | 瓶颈 | 证据 | 现有头部方案为什么没解决 |
|---|---|---|---|
| B1 | **开环 chunk 执行**：一段动作发出去，执行完才看下一帧 | CheckVLA/SV-VLA/VeriVLA 均把“chunk 是开环”作为核心问题 | 大多数 VLA 只在 chunk 边界重规划；没有动作条件后果验证 |
| B2 | **没有评分步骤意识**：模型优化“任务成功”，不优化“第几步值多少分” | UniBot 评分图公开；终局步 39.8%、放置类 59.7% | VLA 的输出是动作，不是步骤状态；不会因为“这一步 40 分”而多试一次 |
| B3 | **通才税**：单模型跨 32 任务/5 轴掉 20–25pp | Table30 专家 vs 通才 | 头部靠更大数据/更大模型/世界模型预训练，边际收益递减 |
| B4 | **真机数据飞轮稀缺**：部署 rollout 很贵 | LoopWAM 用 3 轮 × 30 任务 × ~100 条 ≈ 9,000 条真机 rollout 才 +19.7pp | UniBot 只有少量不计分调试槽；不能照搬“部署-再训练”飞轮 |
| B5 | **单模型 + 远程 API 约束**：不能每任务专家；N 端口；延迟 | 提交 README；单模型赛道 | 头部方案多为“单模型但无运行时裁判”；工程与算法脱节 |

### 2.4 白空间：不是“再大一点”，而是“给通才加一个评分图裁判”

头部方案都在“策略侧”卷：更大模型、更多数据、世界模型预训练、跨本体。它们把**先验**做厚了，但没有解决**执行时的不确定性**。而 UniBot 的评分结构恰好给了我们一个“外部裁判”的接口：

- 我们知道有几步、每步多少分、成功需要哪些步骤；
- 我们知道终局步是闸门；
- 我们知道 human 轴会“做完再撤销”；
- 我们知道 180 秒足够 1–2 次重试。

**所以，最优的边际创新不是“更强的策略”，而是“策略之外的评分感知闭环”。** 这就是 RUBICON。

## 3. 本轮主判断：RUBICON

### 3.1 一句话

**用官方评分图作为世界模型的条件与输出结构，构建一个“动作条件、评分条件、可校准”的 latent 裁判，套在任意强通才 VLA 底座上：chunk 级验证后果、步骤级检测进度/撤销、episode 级分配重试与评估；不追求从零训更大的模型，而是把通才的“通才税”用闭环可靠性补回来。**

### 3.2 三个闭环 + 一个模型

```text
                    ┌────────────────────────────────────────────┐
                    │  UnifoLM-WLA-1.0-Base（6B，冻结 VLM）        │
                    │  ├─ DiT-L action expert（微调，54-dim/30-step）│
                    │  ├─ ER-Flow 动态区域世界模型（复用）          │
                    │  ├─ Rubric Head（新，小）：步骤完成概率/剩余分 │
                    │  └─ Risk Head（新，小）：动作条件预测误差      │
                    └────────────────────────────────────────────┘
                                      │
   语言(160复述) ──► SSG 评分步骤图 ──► 当前步骤 s / 权重 w
                                      │
   4相机+proprio ──► RC-WM：预测未来动态区域 + 步骤信念 b_t
                                      │
                    ┌─────────────────┼─────────────────┐
                    ▼                 ▼                 ▼
              ACV chunk 验证     SARP 分数感知重试   WMD-Ed 评估
              (0.5–1s)           (2–10s)            (episode/离线)
                    │                 │                 │
                    └────────► 动作 chunk / 恢复 ◄──────┘
```

- **ACV（Action-Conditioned Verifier）**：每个 chunk 执行前/执行中，用 RC-WM 预测“这段动作会导致的动态区域/位姿变化”，与实际观测比；风险超过 conformal 阈值就截断后缀、重采样或重规划。
- **SARP（Score-Aware Retry Policy）**：用步骤信念 b_t 和官方权重 w_i，决定“继续/重试当前步/重抓/放弃”，在 180s 预算内最大化期望分数（不是最大化“动作次数”）。
- **WMD-Ed（World-Model Evaluation）**：用同一个 latent 世界模型对一条策略 rollout 做“潜在轨迹评估”，预测成功率/步骤分；只用少量真机调试槽校准，作为发布门和离线筛选。

### 3.3 为什么不是其他四条路

| 路线 | 证据/吸引力 | 为什么不作为主押注 |
|---|---|---|
| **更大的 VLA** | MolmoAct2/GigaBrain/DM0 都在卷 | 边际收益递减；6B 基座已开源；算力/数据不占优；不解决 B1/B2 |
| **WAM 当策略** | DreamZero 14B 7Hz、LingBot 92.9%、Long-WAM 95% | 训练/推理极重；仍是开环 chunk；不知道评分图；远程 API 成本高 |
| **世界模型 RL** | GigaBrain-0.5M* 用 10,000h（6,000h 世界模型生成）+ RAMP | 需要可靠的世界模型模拟器；幻觉会污染策略；UniBot 没有足够真机 RL 回路 |
| **部署-再训练飞轮** | LoopWAM +19.7pp | 需要 ~9,000 条真机 rollout/3 轮；UniBot 调试槽稀缺，不可照搬 |
| **每任务专家/LoRA** | 专家 62% 确实高 | 违反“单模型通才”赛道定义；不可提交 |

**RUBICON 的定位：不跟头部比“先验有多厚”，而是比“执行时有多会纠错、多会分配分数”。** 它是 backbone-agnostic 的：底座可以是 UnifoLM-WLA-1.0、DM0、MolmoAct2 或 GigaBrain；我们只要求底座能输出 action chunk 和视觉特征。

### 3.4 预期收益的算术（可证伪）

设：

- 底座通才成功率 p0 ≈ 0.30（占位量级；外部通才 0.37–0.43 作为上限参考）。
- 一次执行中会出现“可被裁判发现并修复”的关键偏差概率 q ≈ 0.3–0.5。
- 裁判发现并修复的概率 r ≈ 0.4–0.6。
- 误报导致反效果的概率 f ≈ 0.05，伤害 h ≈ 0.2。

则成功率增益近似：

```text
Δp ≈ q·r − f·(1−q)·h
   ≈ 0.4×0.5 − 0.05×0.6×0.2
   ≈ 0.20 − 0.006
   ≈ +19pp   （乐观）
保守：q=0.3, r=0.4, f=0.1, h=0.2 → +12pp − 1.2pp ≈ +11pp
```

这与 CheckVLA（+8.5pp）、VeriVLA（+14.7pp）的量级一致。**保守目标 +5–8pp 成功率，+5–10 步骤分**；如果 T27/T10 调试槽里终局步提升 <5pp，则 ACV 假设不成立，回退到 SSG+SVL。

步骤分增益更好算：终局步占 39.8%，如果裁判把终局步成功率从 p 提到 p+Δ，步骤分至少 +0.4Δ×100；若 Δ=10pp，就是 +4 分；若同时减少“做完被撤销”的假完成，还会多赚。

### 3.5 与第 7 轮的关系：保留骨架，换发动机

| 关系 | 内容 |
|---|---|
| **保留** | SSG 评分步骤图、PGL 放置目标阶梯、OPT 少样本放置位姿迁移、SVL 落点闭环、NRB 官方备注恢复库、L2L 实验室数据、DebugLoop 调试槽 |
| **升级** | SVL（只做落点）→ **ACV**（全 chunk 动作条件验证）；SSG（规则）→ **RC-WM**（学习式步骤信念）；TCLB（离线比较）→ **WMD-Ed**（latent 轨迹评估 + 真机校准） |
| **新增** | **SARP** 分数感知重试、**One-checkpoint Multi-head** 合规架构、**Counterfactual Negatives** 只训裁判不训策略 |
| **修剪** | 从零/大改 GPR-VLA（改用官方 WLA 基座 + LoRA/action expert）；全视频世界模型当策略；世界模型 RL；每任务 LoRA；全 32 任务高保真孪生；把 ICR 缩成 OPT 的检索前端（不再单独做大规模检索系统） |

一句话：**第 7 轮找到了“钱丢在终局放置”；第 8 轮要解决“怎么在任意底座上，稳定地把终局放置和每一步都救回来”。**

## 4. 架构：RUBICON 的五个部件

### 4.1 SSG：评分步骤图（保留，作为骨架）

- 解析 `info.json` 的 `score_steps`，得到每任务线性图 `s0→...→sk` 和权重 w_i。
- 指令匹配：32×5=160 条英文复述 + 中文描述；精确匹配 + 规范化 + 嵌入兜底。
- 运行：只有“谓词头 + 事件校验”确认完成才前进；检测到 human 撤销（进度回退）则回退步骤。
- 作用：给 RC-WM 提供步骤标签/条件；给 SARP 提供权重；给 WMD-Ed 提供评分分解。

### 4.2 RC-WM：评分条件世界模型（新，主押注）

**底座复用**：UnifoLM-ER-Flow 已经能“在当前图像 + 任务/动作条件下预测未来动态区域 token”。我们不重新训一个视频世界模型，而是在它上面加：

1. **动作条件 rollout**：输入当前多视角特征 + 未来 H 步动作 chunk（54 维），预测未来 H 个动态区域 token / 低维 latent；H=1–4 个 chunk。
2. **Rubric Head**：输入当前 VLM 特征 + 预测动态区域 + 当前步骤 s，输出每个步骤的完成概率 \(\hat p_i\)、剩余分数 \(\widehat{SS}=\sum_i w_i \hat p_i\)、成功率 \(\hat S=\prod_i \hat p_i\)（近似）。
3. **Risk Head**：输入“预测动态区域”和“实际观测动态区域”的差异，输出风险分数；用于 ACV。
4. **Uncertainty Head**：预测 epistemic uncertainty；OOD/未见物体时高不确定 → 裁判 abstain，避免误报。

**训练信号**：

- 真实 33k 演示：动作-未来动态区域对（自监督）。
- **反事实负样本**：对真实动作 chunk 做空间偏移/旋转/夹爪翻转/时间错位/截断，保持真实未来作为 target；训练 risk head 区分“动作-观测一致”与“不一致”。这不需要仿真器，也不需要失败演示。
- **官方 human 备注**：T27“叠了第二个之后拿下第二个”、T19“拉上后拉开”、T14“拧开后拧回”等，构造“进度回退”样本；训练 rubric head 的单调性/撤销检测。
- **真机调试槽**：少量真实失败/成功，做校准，不做大规模训练。

**为什么可行**：ER-Flow 已经预训练了“交互会改变哪里”；我们只加小头 + 校准。即使 ER-Flow 的动态区域不够准，risk head 仍可以用特征级预测误差工作；最坏回退到“规则 SSG + 视觉谓词”。

### 4.3 ACV：动作条件验证 + 延迟感知后缀重写（新，主押注）

```python
def act(obs, step, budget):
    # 1) 采样候选 chunk（正常 K=1；高风险/高分步 K=2–4）
    chunks = policy.sample(obs, k=K(step, risk))
    # 2) RC-WM 给每个候选打分
    scores = []
    for a in chunks:
        z_future = rcwm.rollout(obs.features, a, H=2)
        p_step, p_succ, risk, unc = rcwm.heads(z_future, step)
        scores.append(expected_score(p_step, p_succ, risk, unc, step))
    a = chunks[argmax(scores)]
    # 3) 执行 chunk；在每个子段用实际观测更新 risk
    send(a)
    for t in sub_chunks(a):
        obs_t = receive()
        risk_t = rcwm.risk(obs_t, a_remaining)
        if risk_t > tau(step) and unc_t < u_max:
            # 只重写仍可部署的后缀；已执行的前缀保留
            a = policy.replan(obs_t, prefix=a.executed)
            break
    return a
```

- **Conformal 阈值**：用 held-out 名义成功 episode 校准 \(\tau\)，控制“无必要干预”的 episode 级概率 ≤5%；按任务族分层（放置/插入/布料/透明），避免一个阈值打天下。
- **延迟感知**：只重写“还没发出去/还没执行”的后缀；已执行的前缀不回滚。chunk=30（约1s）时，verifier 必须在 <100ms 内给出风险；用 0.3B 头 + 冻结特征，单卡可批处理 N 端口。
- **候选排序**：VeriVLA 已证明“用 latent world model 对候选 chunk 排序”有效；我们的增量是排序目标用**官方步骤分 + 成功率**，不是通用 progress。

### 4.4 SARP：分数感知重试（新，主押注）

在步骤级，维护信念 \(b_t=\{p_i\}\)。每个动作的期望分数：

```text
E[SS] = Σ_i w_i p_i
E[success] ≈ Π_i p_i
```

在时间预算 T（180s，预留 20% 给重试）下，选择：

```text
continue / retry_current / regrasp / abort
```

一个可解释的阈值规则：

```text
retry if  w_s·Δp_s + λ·ΔP_success  >  c_time·(1 + risk_penalty)
```

其中 \(w_s\) 是当前步权重，\(\Delta p_s\) 是重试带来的步骤完成概率提升，\(\Delta P_{success}\) 是成功率提升，λ 是成功率的等价分数（例如 20 分），c_time 是时间成本。**终局步 w_s=40 时，重试的期望收益远高于早期 20/25 分步骤；这解释了为什么 T27/T10 的终局步值得多花 5–10 秒。**

SARP 的输出不是“无脑重试”，而是：

- 高分终局步：允许 1–2 次重试；
- 低分早期步：最多 1 次，优先继续；
- 长程任务（T16/T17/T31）：总重试 ≤2 次，避免超时；
- 检测到 human 撤销：优先恢复被撤销的步骤，而不是从头重做。

### 4.5 WMD-Ed：latent 轨迹评估（新，第二阶段）

PiL-World/ProWorld 用视频世界模型做 policy-in-the-loop 评估，效果好但重。我们只需要**相对排序/回归检测**，不需要生成给策略看的图像。因此用**latent 轨迹评估**：

- 输入：初始观测 + 一条策略 rollout 的动作序列（离线 replay 或在仿真/回放里跑）。
- RC-WM 自回归预测未来 latent/动态区域 + 步骤信念；输出预测成功率、步骤分、各轴风险。
- 用 1–2 个真机调试槽校准（不是训练）：拟合一个小的 isotonic/线性校准，把预测分数映射到真机分数。
- 用途：发布前筛选、A/B 排序、失败挖掘；**不用于最终排名声明**。

**可行性**：不需要图像生成；ER-Flow 的 latent 已有；推理成本低。**风险**：latent 评估可能低估接触失败；用真机校准 + 保守阈值；若相关系数 <0.8，关闭。

### 4.6 One-checkpoint Multi-head：单模型合规

官方只说“单模型多任务”，没有形式化定义“一个 checkpoint 内是否允许辅助头”。我们按最保守的方式设计：

- 一个提交 artifact：UnifoLM-WLA-1.0-Base + 微调后的 action expert + RC-WM/Rubric/Risk 头，全部在一个 checkpoint 目录/一个 `Policy` 类里。
- 所有学习组件共享同一个冻结 VLM backbone；新增头是小模块（<5% 参数）。
- 确定性代码（SSG/PGL/SVL 的几何/规则部分）不进模型，作为推理服务逻辑；在模型卡中披露。
- 如果官方明确“只能有一个前向网络”，则把 RC-WM/Rubric/Risk 头蒸馏进 action expert 的 cross-attention（辅助 token），仍然是一个前向。

**这是本轮必须提前问官方的问题**（见 §12）。如果规则不允许任何辅助学习组件，回退方案是“纯 SSG + 视觉谓词 + SVL”，仍然能吃到一部分终局步收益，但放弃世界模型裁判的主要增益。

## 5. 形式化：把“评分图”变成 POMDP

### 5.1 状态与信念

- 真实状态 \(x_t\)：物体位姿、夹爪、接触、步骤完成情况。
- 观测 \(o_t\)：4 路 RGB + proprio + EE + gripper。
- 信念 \(b_t = \{p_i\}_{i=1..K}\)：第 i 步完成概率；由 RC-WM 的 Rubric Head 输出。
- 步骤图 \(G=(V,E,w)\)：官方 `score_steps`；成功 = 所有节点完成。

### 5.2 世界模型

\[
z_{t+1:t+H} = f_\theta(z_t, a_{t:t+H}, l, s_t)
\]

\[
\hat p_{i,t} = \sigma(g_\phi(z_t, l, s_t, i)), \quad
\widehat{SS}_t = \sum_i w_i \hat p_{i,t}, \quad
\hat S_t = \prod_i \hat p_{i,t}
\]

其中 \(f_\theta\) 复用 ER-Flow 的动态区域预测，\(g_\phi\) 是 rubric head。训练损失：

\[
L = L_{dyn} + \lambda_1 L_{step} + \lambda_2 L_{cal} + \lambda_3 L_{mono} + \lambda_4 L_{risk}
\]

- \(L_{dyn}\)：预测未来动态区域 token（ER-Flow 原有）。
- \(L_{step}\)：步骤完成 BCE（弱标签来自 DTW/事件谓词）。
- \(L_{cal}\)：校准（温度/isotonic 的软约束，或训练后校准）。
- \(L_{mono}\)：步骤概率单调性（除检测到撤销）。
- \(L_{risk}\)：动作条件一致性（正样本真实动作，负样本扰动动作）。

### 5.3 控制目标

\[
\max_{\pi} \; \mathbb{E}\left[ \sum_i w_i \mathbf{1}[\text{step } i \text{ done}] + B \cdot \mathbf{1}[\text{all done}] - \mu \cdot \text{time} \right]
\]

B 是成功 bonus（排行榜同时看成功率和步骤分；B 可设为 20–30 分等价）。SARP 用一步 lookahead 近似这个目标；不需要完整 POMDP 求解。

### 5.4 为什么“评分条件”会优于“任务条件”

- 任务条件只告诉模型“做什么”；评分条件告诉模型“哪一步值钱、现在第几步、是否被撤销”。
- 同一观察下，评分条件会改变动作选择：例如 T27 已经叠好碗1/碗2，当前碗3（40分）——模型应更保守、更愿意重试；而早期碗1（30分）可以更快。
- 这把“测试时算力”分配给高价值步骤，而不是平均分配。

## 6. 数据与训练：只训裁判，不训策略的“反事实负样本”

### 6.1 数据来源

| 数据 | 用途 | 规模 | 备注 |
|---|---|---|---|
| 官方 33k 演示 | 动作-动态区域自监督；步骤标签 | 169h | 只用官方数据即可起步 |
| 反事实负样本 | risk head 的动作条件一致性 | 每任务 1–2k | 对真实动作做扰动，不需要仿真 |
| 官方 human 备注 | 撤销/恢复样本 | 32 任务 × 2 剧本 | T27/T19/T14/T17 等 |
| TCLB/仿真 rollout | 失败样本、候选排序 | 8 放置任务 | 只做相对比较 |
| 调试槽真机 | 校准/验证 | 1–2 槽 | 不作为大规模训练 |

### 6.2 反事实负样本怎么造

对一条真实演示的某个 chunk：

1. **空间偏移**：EE 目标平移 2–10cm / 旋转 5–30°。
2. **夹爪翻转**：开/合取反。
3. **时间错位**：把 chunk 向前/向后错 5–30 帧。
4. **截断/拼接**：用另一个任务的 chunk 替换。
5. **速度缩放**：0.5×/2×。

保持真实未来观测作为 target。正样本是真实动作；负样本是扰动动作。训练 risk head 预测“动作-观测不一致”。这不需要失败演示，也不需要仿真器；它学的是“这段动作能否解释看到的未来”。在推理时，如果策略输出的动作与真实动态不匹配，risk 高。

### 6.3 步骤标签怎么来

- 用第 7 轮 TLE 的 DTW/事件谓词：每任务取 20–50 条演示，按“物体进入目标区域/夹爪闭合/容器闭合/拉链到位”等事件切分；得到每帧的步骤序号。
- 对 32 任务抽检 10%；不一致的用人工修正。
- 对 human 撤销，用 NRB 剧本显式标注“进度回退”。

|---|---|---|---|
| 0 | 官方 33k | 复现 WLA 基线 action expert | held-out 动作误差不降 |

### 6.5 算力

- 基座微调：官方 recipe 单张 24GB，冻结 VLM；1–2 周。
- 特征提取：33k × 4 视角，抽 5–10Hz；1–2×A100/H100，2–4 天；存储约 20–40GB。
- RC-WM 头：0.3–1B，1–2×A100/H100，3–5 天。

## 10. 创新点清单（持续迭代）

> 状态：押注=本轮主线；保留=沿用；升级=旧点改造；降级=保留但非主回路；砍=不做。

### I1 RC-WM：评分条件世界模型（新增，押注）
- **动机**：官方评分图公开；终局步是闸门；现有世界模型不预测步骤分/撤销。
- **差异**：条件=语言+当前步骤+官方权重；输出=未来动态区域+步骤信念+剩余分；复用 ER-Flow，不生成视频。
- **可行性**：ER-Flow 已有动态区域预测；33k 数据；小头训练。
- **资源**：1–2×A100/H100，3–5 天；特征缓存 20–40GB。
- **步骤**：步骤标签→动态区域特征→rubric/risk 头→校准→接 SSG。
- **风险**：标签噪声；OOD；→ 分桶 + abstain + 回退。

### I2 ACV：动作条件 chunk 验证（新增，押注）
- **动机**：开环 chunk 是误差放大器；仅观测异常无法区分“预期变化”和“异常变化”。
- **差异**：用 RC-WM 预测“这段动作的后果”，conformal 阈值，只重写可部署后缀。
- **可行性**：CheckVLA/SV-VLA/VeriVLA 证据；326ms→可压到 <100ms。
- **资源**：无额外数据；1 张 GPU；服务端异步。
- **步骤**：候选 chunk→RC-WM 打分→风险触发→后缀重写→A/B。
- **风险**：误报/延迟；→ 5% conformal + p99 预算。

### I3 SARP：分数感知重试（新增，押注）
- **动机**：排行榜同时看成功率和步骤分；180s 预算有限；不该平均分配重试。
- **差异**：用官方 w_i + 步骤信念做期望分数最大化；终局步优先；长程任务限次。
- **可行性**：规则+阈值即可；不需要新模型。
- **资源**：CPU；离线校准。
- **步骤**：信念→期望分→阈值→预算守卫→调试槽验证。
- **风险**：重试超时/误判；→ 预算守卫 + 双阈值。

### I4 WMD-Ed：latent 轨迹评估（新增，第二阶段）
- **动机**：真机调试槽稀缺；视频世界模型评估太重；需要发布前筛选。
- **差异**：latent rollout + 评分分解；只做相对排序；用少量真机校准。
- **可行性**：PiL-World/ProWorld 证明相关性；我们省掉图像生成。
- **资源**：RC-WM 复用；1 张 GPU；1–2 调试槽。
- **步骤**：离线 rollout→预测分数→校准→发布门。
- **风险**：低估接触失败；→ 相关性 <0.8 关闭。

### I5 One-checkpoint Multi-head（新增，合规）
- **动机**：单模型赛道；辅助头可能被质疑。
- **差异**：一个 checkpoint、共享冻结 VLM、小头 <5% 参数；全部披露。
- **可行性**：官方微调 recipe 已冻结 VLM；加头容易。
- **资源**：工程 1 人周。
- **步骤**：头接入→checkpoint 打包→模型卡→审计。
- **风险**：规则变化；→ 可蒸馏进 action expert。

### I6 Counterfactual Negatives（新增，数据）
- **动机**：官方数据全是成功；risk head 需要负样本。
- **差异**：对真实动作做扰动，保留真实未来；不需要仿真/失败演示。
- **可行性**：纯离线；成本低。
- **资源**：CPU/GPU 数据增强。
- **步骤**：扰动库→正负对→训练→AUROC。
- **风险**：扰动不真实；→ 混合 NRB/仿真失败。

## 0. 执行摘要

### 0.1 问题

UniBot 的评分结构是公开的：32 个任务、每任务 2–5 个评分步骤、满分 100；成功=所有步骤完成；终局步骤合计 **39.8%** 的分数，放置/插入/堆叠/闭合类步骤约 **59.7%**。排行榜同时看成功率和步骤分。但现有通才 VLA 的典型问题是：

1. **开环 chunk 执行**：一段动作发出去，执行完才看下一帧；小误差在 chunk 内放大。
2. **没有评分步骤意识**：策略优化“任务成功”，不优化“第几步值多少分”，也不会因为终局步 40 分而多试一次。
3. **通才税**：外部真机基准 Table30 上，专家模型 62%–64%，单模型通才只有 37%–43%，差 20–25pp。
4. **真机飞轮稀缺**：LoopWAM 用约 9,000 条真机 rollout 才 +19.7pp；UniBot 只有少量不计分调试槽，不能照搬。
5. **单模型 + 远程 API**：不能每任务专家；N 端口；延迟不确定。

### 0.2 方案

**RUBICON = Rubric-Conditioned World Model + Action-Conditioned Verifier + Score-Aware Retry Policy + World-Model Evaluation。**

- **底座**：`UnifoLM-WLA-1.0-Base`（6B，Apache-2.0，6B/2,500h/64 任务；冻结 VLM，微调 DiT-L action expert + robot-state projector；单张 24GB 可微调）。
- **世界模型**：复用 ER-Flow 的“交互中心动态区域预测”，加动作条件 rollout、评分头、风险头、不确定性头；**不生成完整未来视频**。
- **ACV**：每个 chunk 用 RC-WM 预测后果，和实际观测比；conformal 阈值触发后缀重写。
- **SARP**：用官方步骤权重和步骤信念，在 180s 预算内分配“继续/重试/重抓/放弃”。
- **WMD-Ed**：用同一个 latent 世界模型做 rollout 评估，少量真机调试槽校准，做发布门。
- **合规**：一个 checkpoint、共享冻结 VLM、辅助头 <5% 参数；所有学习组件披露；必要时蒸馏进 action expert。

### 0.3 预期

- 保守：成功率 **+5–8pp**，步骤分 **+5–10 分**。
- 乐观：成功率 **+10–15pp**，步骤分 **+8–15 分**（对齐 CheckVLA +8.5pp、VeriVLA +14.7pp 的量级）。
- 成本：比从零训 6B VLA 低一个量级；最小版本单张 24GB 可跑。
- 证伪：T27/T10 调试槽终局步 <5pp → 关闭 ACV；步骤 F1 <0.7 → 只做放置桶；WMD-Ed 相关性 <0.8 → 关闭。

### 0.4 关键纠正

**“榜首 29.7%、不到 30%”是占位数据，不是真实榜单。** `leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`，256 条 task_metrics 由脚本生成，详情页 32 个任务视频均为「测试视频占位」。真实榜单仍为 Coming Soon。本报告只把占位名单当作“模型家族”的代表，不用其数字排名；真实先验来自 RoboChallenge Table30 与公开论文。

### 3.2 一次 `get_action` 的时序

```text
t0  receive obs_t (4 RGB, proprio, language)
t1  encode z_t (frozen VLM)                      ~10–30ms
t2  SSG: language→task, step s, weights w        <1ms
t3  policy: sample K chunks (K=1 normal; 2–4 high-risk/high-value)
t4  RC-WM: rollout H=1–2 chunks; rubric/risk/unc ~30–60ms
t5  select a* by expected score
t6  send a*; execute chunk (default 30 steps @30Hz ≈ 1s)
t7  every sub-chunk: obs→risk; if risk>τ and u<u_max:
       replan suffix; keep executed prefix
t8  return next chunk
```

**延迟预算**：t1+t2+t4 ≤100ms p99（单卡批处理 N 端口）；动作 chunk 执行 1s 给足余量。若 p99 超预算，降 K、降 H、用 0.3B 头或异步。

## 4. 组件详设

### 4.1 SSG：评分步骤图

**输入**：32 个 `info.json` + 160 条英文复述 + 中文描述。  
**输出**：每任务线性步骤图 `G=(V,E,w)`，节点=步骤，权重=官方分值；当前步骤 s、步骤信念 b。

```python
class RubricGraph:
    def __init__(self, task_info):
        self.steps = task_info["score_steps"]      # [{desc, score}, ...]
        self.weights = [s["score"] for s in self.steps]
        self.K = len(self.steps)

    def match(self, language: str) -> str:
        # exact -> normalized -> sentence-embedding fallback
        ...

    def advance(self, s, obs, belief):
        # deterministic predicates + event detector; require 2 consecutive frames
        if self.predicate[s](obs) and self.event[s](obs):
            return s + 1
        return s

    def regress(self, s, obs):
        # human undo / progress reversal; NRB scripts
        if self.undo_detector[s](obs):
            return max(0, s - 1)
        return s
```

**防跳步/假完成**：步骤前进需要“谓词 + 事件”双确认；连续 2 帧；终局步额外要求稳定 3 帧（防“放进去又掉出来”）。  
**撤销检测**：T27 第二碗被拿走、T19 拉链被拉开、T14 药瓶被拧回；用 NRB 剧本 + 视觉差异 + 步骤信念回退。

### 4.2 RC-WM：评分条件世界模型

#### 4.2.1 复用 ER-Flow

UnifoLM-ER-Flow 的核心是“交互中心世界建模”：

1. 从相邻帧提取光流，得到动态区域；
2. 用 VQ-VAE 把动态区域离散成 token；
3. 以当前图像 + 任务/动作描述为条件，让 VLM 预测未来动态区域 token；
4. 这些 token 作为“世界知识”注入动作生成。

我们不重新训一个视频扩散模型，而是：

- 保留 ER-Flow 的动态区域 encoder / codebook / predictor；
- 加一个 **action adapter**：把 54×30 的动作 chunk 编码成 action token，cross-attend 到 VLM 特征；
- 加 **multi-step rollout**：H=1–4 个 chunk，自回归预测动态区域 token；
- 加 **rubric/risk/uncertainty heads**。

#### 4.2.2 形式化

\[
z_t = \text{VLM}_\text{frozen}(o_t, l)
\]

\[
u_{t:t+H} = \text{ActionEnc}(a_{t:t+H}) \in \mathbb{R}^{H \times d}
\]

\[
\hat{d}_{t+1:t+H} = f_\text{ER-Flow}(z_t, u_{t:t+H}, s_t, l)
\]

\[
[\hat{p}_1,\dots,\hat{p}_K], \widehat{SS}, \hat{S}, r_t, u_t
= g_\text{heads}(z_t, \hat{d}_{t+1:t+H}, s_t)
\]

其中 \(\hat p_i=P(\text{step }i\text{ done})\)，\(\widehat{SS}=\sum_i w_i \hat p_i\)，\(\hat S=\prod_i \hat p_i\)（近似独立），\(r_t\) 是风险，\(u_t\) 是不确定性。

#### 4.2.3 网络结构

```text
VLM tokens (frozen) ──┐
language tokens ──────┤
step embedding s ─────┤──► FiLM/Cross-Attn ──► Rubric Head (2-layer Transformer)
predicted dyn tokens ─┘                         ├─ K step logits
                                                ├─ remaining score (regression)
                                                └─ success logit

predicted dyn tokens ──┐
observed dyn tokens ───┤──► Risk Head (MLP + cosine/L2) ──► risk
action tokens ────────┘

VLM pooled z_t ───────► Uncertainty Head (ensemble/energy) ──► u
```

**参数预算**：Rubric Head ~50M；Risk Head ~20M；Uncertainty Head ~10M；Action Adapter ~100M；总计 <5% of 6B。冻结 VLM，只训这些 + DiT-L LoRA。

#### 4.2.4 训练目标

\[
L = L_\text{dyn} + \lambda_1 L_\text{step} + \lambda_2 L_\text{cal} + \lambda_3 L_\text{mono} + \lambda_4 L_\text{risk} + \lambda_5 L_\text{unc}
\]

- \(L_\text{dyn}\)：未来动态区域 token 的交叉熵/对比（ER-Flow 原有）。
- \(L_\text{step}\)：步骤 BCE；弱标签来自 DTW/事件；正负样本按帧。
- \(L_\text{cal}\)：校准损失（预测概率 vs 经验频率；温度/isotonic 的软约束）。
- \(L_\text{mono}\)：步骤概率单调性（无撤销时 \(p_i \ge p_{i-1}\) 的 hinge）。
- \(L_\text{risk}\)：动作条件一致性；正样本真实动作，负样本扰动动作；BCE。
- \(L_\text{unc}\)：不确定性校准（高误差样本高不确定）。

**分阶段训练**：先 \(L_\text{dyn}\) 适应新数据；再加 \(L_\text{step}\)；再加 \(L_\text{risk}\)；最后校准。避免一开始多任务冲突。

#### 4.2.5 推理时的“动作条件”

- **候选排序**：给定 K 个候选 chunk，分别 rollout，取期望分最高。
- **风险触发**：实际执行后，用实际观测算 observed dynamic tokens，和 predicted 比；risk 高则重规划。
- **反事实**：如果候选 A 的预测步骤分低于候选 B，但风险更高，选 B；不是只看“像不像训练数据”。

### 4.3 ACV：Action-Conditioned Verifier

#### 4.3.1 算法

```python
def rubicon_act(obs, session, budget):
    s = session.step
    w = session.weights
    K = 4 if (w[s] >= 35 or session.risk > 0.6) else 1

    chunks = session.policy.sample(obs, k=K)
    best, best_score = None, -inf

    for a in chunks:
        z_future = session.rcwm.rollout(obs.z, a, H=2)
        p_step, p_succ, risk, unc = session.rcwm.heads(z_future, s)
        score = expected_score(p_step, p_succ, w, risk, unc, budget)
        if score > best_score:
            best, best_score = a, score

    session.send(best)
    executed = 0

    for sub in range(session.sub_chunks):
        obs_t = session.recv()
        executed += sub
        r = session.rcwm.risk(obs_t, best[executed:])
        if r > session.tau[s] and obs_t.unc < session.u_max:
            # keep executed prefix; rewrite only the deployable suffix
            best = session.policy.replan(obs_t, prefix=best[:executed])
            session.record_intervention(s, r)
            break

    return best
```

#### 4.3.2 Conformal 阈值

- 用 held-out 名义成功 episode 校准每个任务族的阈值 \(\tau_f\)，目标是“无必要干预”的 episode 级概率 ≤5%。
- 任务族：放置（T27/T15/T18/T21...）、插入（T10/T25...）、布料（T02/T06/T29...）、透明/小件（T22/T23/T24...）、长程（T16/T17/T31...）。
- 每个族至少 30 条校准 episode；不足则用全局阈值 + 保守系数。
- 干预代价不对称：漏检（失败）代价高，误报（多余重规划）代价低；用 \(c_\text{FN}/c_\text{FP}=5\) 的加权分位数。

#### 4.3.3 延迟优化

| 手段 | 效果 | 代价 |
|---|---|---|
| 0.3B 小头 + 冻结特征 | <30ms | 需蒸馏/特征缓存 |
| 异步：当前 chunk 执行时算下一个 | 隐藏 1s 延迟 | 需双缓冲 |
| 批处理 N 端口 | GPU 利用率 | 需会话隔离 |
| H=1（只验下一个 chunk） | 减半 | 长程略弱 |
| 低分辨率 wrist / 高分辨率 head | 减 token | 可能漏小件 |
| 量化/FP16 | 2× | 精度略降 |

**目标**：p99 ≤100ms；若达不到，先降 K/H，再降模型，不牺牲 conformal 阈值。

### 4.4 SARP：Score-Aware Retry Policy

#### 4.4.1 目标

\[
\max_{\pi} \; \mathbb{E}\left[\sum_i w_i \mathbf{1}[\text{step}_i] + B \cdot \mathbf{1}[\text{all}] - \mu T\right]
\]

\(B\)=20–30 分等价（成功 bonus）；\(\mu\)=时间惩罚；\(T\)=180s。

#### 4.4.2 一步 lookahead

在步骤 s，比较：

```text
continue:   Q_c = w_s·p_s + Σ_{i>s} w_i·p_i + B·Π p_i
retry:      Q_r = w_s·p_s' + Σ_{i>s} w_i·p_i' + B·Π p_i' − c_r
regrasp:    Q_g = ... − c_g
abort:      Q_a = current step score
```

选择 argmax；其中 \(p_s'\) 是重试后的步骤完成概率（由 RC-WM 估计或历史统计），\(c_r\) 是时间成本。

**简化阈值**：

```text
retry if  w_s·(p_s'−p_s) + B·(P_success'−P_success) > c_time·(1+risk_penalty)
```

#### 4.4.3 预算守卫

- 总重试时间 ≤30s（180s 的 1/6）。
- 长程任务（T16/T17/T31）≤2 次；短任务（T05/T11/T12）≤3 次。
- 终局步允许 1–2 次；早期步最多 1 次。
- 检测到 human 撤销：优先恢复，不计入“普通重试”预算，但总时间仍受限。
- 超时前 20s：只做“高价值终局步”重试；否则收尾。

### 4.5 WMD-Ed：Latent Trajectory Evaluation

#### 4.5.1 为什么不做视频生成

PiL-World/ProWorld 生成视频是为了把观测喂回策略（policy-in-the-loop）。我们只需要**评估一条固定策略的 rollout**，不需要生成给策略看的图像。因此用 latent 轨迹评估：

- 输入：初始观测 + 动作序列（离线 replay 或仿真/回放）。
- RC-WM 自回归预测 latent/动态区域 + 步骤信念；输出预测成功率/步骤分/轴风险。
- 用少量真机调试槽做**校准**（isotonic/线性），不是训练。
- 用途：发布前筛选、A/B 排序、失败挖掘；不做最终排名声明。

#### 4.5.2 校准

```python
# 收集 n 个调试槽 episode: (pred_success, real_success, pred_step, real_step)
cal = IsotonicRegression(out_of_bounds="clip")
cal.fit(pred_success, real_success)
# 报告: R², Spearman, ECE; 若 Spearman <0.8 关闭
```

#### 4.5.3 与真机评测的关系

- WMD-Ed 只做**相对排序**：候选 A vs B，不承诺绝对成功率。
- 每次发布前，用 1–2 个调试槽验证排序一致性；若不一致，人工看失败视频。
- 真实计分跑仍是唯一权威；WMD-Ed 不替代。

### 4.6 单模型合规：One-checkpoint Multi-head

```text
submission/
  policy.py                 # class Policy: reset(), get_action()
  checkpoint/
    vlm/                    # frozen UnifoLM-WLA VLM
    action_expert/          # LoRA + DiT-L
    rubric_head.pt          # 50M
    risk_head.pt            # 20M
    uncertainty_head.pt     # 10M
    action_adapter.pt       # 100M
  config.yaml
  MODEL_CARD.md             # 披露所有学习组件、数据、许可
```

- 一个 `Policy` 类、一个 checkpoint 目录、一次加载。
- 所有学习组件共享冻结 VLM；辅助头 <5% 参数。
- 确定性代码（SSG/PGL/SVL 几何）作为推理逻辑，不进模型；在模型卡中说明。
- 若官方要求“单次前向”，把辅助头蒸馏进 action expert 的 cross-attention 辅助 token；仍然是一个前向。
- 若官方禁止任何辅助学习组件：回退“SSG + 视觉谓词 + SVL”，放弃 RC-WM/ACV 主增益。

## 11. 关键伪代码

### 11.1 训练一个 batch

```python
def train_step(batch):
    obs, lang, actions, future_frames, step_labels, step_ids = batch
    # frozen VLM
    with torch.no_grad():
        z = vlm(obs, lang)                      # [B, T, D]
        dyn_obs = dynamic_region_encoder(future_frames)  # [B, H, N]

    # action adapter + ER-Flow rollout
    u = action_adapter(actions)                 # [B, H, d]
    dyn_pred = er_flow_predictor(z, u, step_ids)  # [B, H, N]

    # heads
    p_step, ss, succ, risk, unc = heads(z, dyn_pred, step_ids)

    loss = (
        ce(dyn_pred, dyn_obs)
        + 1.0 * bce(p_step, step_labels)
        + 0.5 * mse(ss, ss_target)
        + 0.5 * bce(succ, success_target)
        + 0.2 * mono_loss(p_step)
        + 0.5 * bce(risk, risk_target)
        + 0.1 * unc_loss(unc, error)
    )
    loss.backward()
    optimizer.step()
```

### 11.2 一次推理

```python
@torch.no_grad()
def get_action(self, obs):
    z = self.vlm(obs, obs.language)
    s = self.ssg.update(obs, self.belief)
    K = 4 if self.weights[s] >= 35 or self.risk > 0.6 else 1

    best = None
    for a in self.policy.sample(z, k=K):
        dyn = self.rcwm.rollout(z, a, H=2)
        p, ss, succ, risk, unc = self.heads(z, dyn, s)
        score = self.expected_score(p, ss, succ, risk, unc, s)
        if best is None or score > best.score:
            best = (a, score, risk, unc)

    self.send(best.a)
    return best.a
```

### 11.3 风险触发

```python
def on_sub_chunk(self, obs_t, remaining):
    dyn_obs = self.dynamic_region_encoder(obs_t)
    dyn_pred = self.last_pred[:, self.executed]
    r = self.risk_head(self.last_z, dyn_pred, dyn_obs)
    if r > self.tau[self.step] and self.unc < self.u_max:
        self.policy.replan(obs_t, prefix=self.executed)
        self.interventions += 1
```
