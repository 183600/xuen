# 第 4 轮（灵感循环第 4 轮；本轮灵感：「安全交互」×「用户共创」）

> **基线**：第 3 轮 InstructGauge（IP-321–327；定义 432–447；引理 51–58；实验 E441–E456）。第 1–2 轮 MODGAUGE / LeanGauge / ToolGauge 骨架继续继承不变。
> 本轮纪律：**增量升级 + 严格退化**。两个新灵感各沿一条轴升级 InstructGauge：安全交互升级「人—机接口」，用户共创升级「能力来源」；任一环节不可用都必须能一键退回，二者都是增强项、不是依赖项。

## 0. 直觉与动机

**灵感 1（安全交互 → 把「人」也当作需要被治理的不可靠组件，而不是安全的外部假设）**
直觉：过去三轮把安全几乎都放在机器人一侧——硬约束、盾、证书、共形覆盖。但真实的修复/探测现场是**人机共同作业**：人随时会打断、误操作、越权、注意力耗尽，或者反过来过度信任系统。交互安全不是「机器人别撞人」这一条物理约束，而是**交互本身可治理**：每个输入可归属、可中断、有明确权限、有同意/接管状态、且不超出人的注意力预算。关键的反直觉点是：**不能把安全寄托在人的警觉上**——自动化越可靠，人越容易陷入监控疲劳与模式混淆（ironies of automation）。所以必须把「人」当作一个有授权但不可靠、需要接口级保护的组件。

**灵感 2（用户共创 → 能力不再只由设计者给定，而是由用户持续供给；这既是覆盖率的来源，也是安全边界的腐蚀源）**
直觉：盲区千差万别，靠设计者预先枚举工具/目标永远不够。用户共创让一线用户教新技能、补新场景、贡献新回执与校准样本——这是把覆盖率从「设计者想象」扩展到「真实长尾」的唯一可持续方式。但共创本质上是一条**能力供应链**：用户提交的是可执行的能力增量，而不是普通数据。若把共创直接接进实时闭环，就等于把第 3 轮的「能力闭包」拆掉——任何用户都能扩大物理可行域。正确的做法不是禁止共创，而是把它当作**带签名的软件包**：可以自由提交，只能在隔离区构建，必须通过固定安全回归、法定人数、影子执行与风险预算，才能在静默点「安装」，且永远可卸载/回滚。

**灵感 3（两者耦合 → 最危险的不是一次恶意输入，而是「权限蠕变」与「责任稀释」）**
直觉：安全交互要求人随时能介入，用户共创又鼓励人不断提出新能力——两者叠加会产生一种慢性风险：每一次小的范围扩张都「看起来合理」，许多用户各自贡献一点，系统能力边界就在无人作恶的情况下被逐步推宽（normalization of deviance）；同时「大家都参与了」会让责任归属变得模糊（responsibility diffusion）。因此耦合处的结构不是更强的过滤器，而是三条治理结构：**双通道权限**（实时通道仍能力闭包，共创通道无执行器通路）、**风险预算 + 权限蠕变检测**（扩张要付费、有上限、会被冻结审计）、**唯一安全责任人 + 出处账本**（每个动作可追溯到贡献者集合与一个具名安全 owner，责任不可稀释）。

## 1. 研究问题（本轮要回答什么）

- **Q1（交互安全的口径）**：在人机共同作业中，「安全交互」能否被写成一组可在线检查的不变量（可归属 / 可中断 / 有同意 / 权限内 / 注意力预算内），并由一个交互盾强制执行，而不是依赖人的警觉？
- **Q2（共创的准入条件）**：用户共创必然扩张能力；在什么准入条件下，能力扩张不会破坏第 3 轮的能力闭包与安全保证，且收益（覆盖率 / 长尾任务）可量化？
- **Q3（耦合的慢性风险）**：当共创进入实时闭环，权限蠕变与责任稀释是否可被结构性地界定与检测？能否用风险预算、法定人数、可撤销账本把「边界漂移」压回有限、可审计的范围？

## 2. 三条设计原则（雏形，正式化见产物区定义 448–463）

**P4 双通道权限（Two-Channel Authority）**
实时通道只允许在**已准入能力账本**内做选择与排序，保持第 3 轮能力闭包；共创通道可以提出超出当前账本的类型化能力增量，但**没有任何直达执行器的路径**，只能在沙箱中构建。扩张与执行在时间与权限上分离：实时通道永远不等待共创，共创永远不能直接动执行器。

**P5 交互安全契约（Interaction Safety Contract）**
任何被接受的交互必须满足五元组：可归属（attributable）、可中断（interruptible within τ_int）、有同意或可逆（consented ∨ reversible）、权限内（within authority）、注意力预算内（within attention budget）。违反任一项 ⇒ 交互盾降级到第 3 轮默认接口或安全停机；绝不以「人已经确认」替代结构约束。

**P6 治理式可撤销准入（Governed, Revocable Admission）**
共创能力只有通过「固定安全回归 + 法定人数/多样性 + 影子执行 + 风险预算」四重门才能进入账本；每次准入产生可撤销证书，撤销只在静默点执行并重新验证依赖计划。**能力扩张必须付费**：每个增量消耗风险预算 `r(κ)`，预算耗尽即冻结准入，触发审计。

## 3. 与基线的接口（如何退化）

- 交互监护器不可用 ⇒ 交互退化为第 3 轮 InstructGauge 的 `Γ` 接口（人仍是指令源，但只享受能力闭包保护）；
- 沙箱/影子执行不可用 ⇒ 冻结账本，禁止任何新准入，只运行已准入能力（等价于 InstructGauge 固定工具集）；
- 法定人数/多样性证据不足 ⇒ 不晋升，保留旧账本；必要时撤销最近一次准入；
- 贡献者分层样本不足 ⇒ 回退第 3 轮全局/指令分层共形阈值；
- 权限蠕变检测触发 ⇒ 冻结晋升并要求具名安全 owner 复核；
- CoGauge 失效 ⇒ InstructGauge ⇒ ToolGauge ⇒ LeanGauge ⇒ MODGAUGE 原样。

## 4. 预期贡献

1. 一个把「人」纳入安全论证的**交互安全契约**与在线交互盾，明确可归属/可中断/同意/权限/注意力五类不变量；
2. 一个**双通道权限**架构：在不破坏第 3 轮能力闭包的前提下，允许用户共创扩张能力，扩张只经认证晋升进入账本；
3. 一套**治理式准入 + 可撤销账本**：固定安全回归、法定人数/多样性、影子执行、风险预算、静默点回滚，抵抗单点恶意与治理捕获；
4. 一个**贡献者分层加权共形校准**，修正共创数据的非可交换性，并给出覆盖随分布漂移的退化界；
5. 一条完整可证伪路径：E457–E472 覆盖实时能力闭包、晋升门、捕获/投毒、权限蠕变、中断接管、注意力背压、分层覆盖、撤销等价与 50Hz 时序。

## 5. 本轮最大风险

**一句话**：用户共创最危险的失败不是「一个恶意技能被放进来」，而是「许多小的、各自看似合理的范围扩张」在责任被稀释的治理结构里逐步推宽安全边界；因此本轮真正的残余风险在**准入治理被捕获或审计疲劳**，而不是单个沙箱或单个盾的强度。

## 2. 形式化定义（要点）

**定义 448（交互契约 IC）** `IC = (A_h, A_r, Auth, Cons, τ_int, λ_max)`。`A_h` 为人可发出的交互动作（指令、接管、急停、共创提交、撤销请求），`A_r` 为系统可发出的请求/提示；`Auth ⊆ A_h × Role` 为权限关系，必须存在唯一根安全责任人 `o_safe`；`Cons` 为同意/接管状态自动机；`τ_int` 为从人发出接管到系统进入安全恢复态的最大时延；`λ_max` 为注意力预算。`IC` 合法当且仅当 `Auth` 是偏序、`Cons` 无不可达吸收态、`τ_int ≤ τ_max`。

**定义 449（交互安全关系 SafeInt）**
`SafeInt(σ, h) ⇔ attributable(h) ∧ within_authority(h, Auth) ∧ interruptible(σ, τ_int) ∧ (reversible(h) ∨ consented(h, Cons)) ∧ load(σ) ≤ λ_max`。
系统在实时通道上必须保持 `SafeInt`；任一合取项失败 ⇒ 交互盾输出 `DEGRADE`（退回第 3 轮默认 `ι₀` 与 K=1）或 `SAFE_STOP`。**关键**：`consented(h)` 不能替代 `within_authority(h)`——人的确认只解除「可逆性」要求，不解除权限与能力闭包。

**定义 450（双通道权限 TCA）** 权限宇宙 `U = U_live ⊎ U_stage`，且 `reach(U_stage) ∩ Actuator = ∅`。实时计划满足
`Plan_live(ℓ, t) ⊆ Plan(CC ∪ L_t)`，
其中 `CC` 为第 3 轮能力闭包、`L_t` 为时刻 `t` 的已准入账本。唯一允许的跨通道操作是
`Promote: U_stage × L_t × Q → L_{t'} ∪ {⊥}`，
且只在 `q_quiesce`（第 3 轮定义 439）提交。故共创不能在实时块内扩大可行域。

**定义 451（共创贡献 κ 与类型化能力增量）** `κ = (demo, p, S, E, sig, ts)`，其中 `S = Δcap(κ)` 必须用与第 3 轮 `O_onto / T₀ / M_phys` 相同的**类型化本体**表达（新工具、新目标、新可测谓词、新幅值包线），禁止自由文本直达执行器。`provenance(κ)` 给出从原始演示到候选技能的可验证出处链；`sig` 为贡献者签名。

**定义 452（能力账本 L 与风险预算 R）** `L = (adm, rev, ver, owner)`：已准入技能、已撤销技能、版本 DAG、每个已准入技能的唯一安全 owner。风险预算
`R(L) = Σ_{a ∈ adm} r(a) − Σ_{a ∈ rev} r(a)`，
准入要求 `R(L) + r(κ) ≤ R_max`。不变量：`∀t, R(L_t) ≤ R_max`。撤销返还预算，但撤销本身必须附 `RevCert` 并重验依赖。

**定义 453（法定人数与多样性支持）** 贡献者权重取可靠性的保守下界 `w_p = LCB(reliability(p))`，
`support(κ) = Σ_{p ∈ P} w_p · 1[κ endorsed by p]`。
晋升要求 `support(κ) ≥ q` 且支持者至少覆盖 `2f_max + 1` 个独立贡献者簇（或多样性 `D(support) ≥ D_min`），以抵抗单一用户/单一组织对能力账本的捕获。原始提交数不计入支持，只有经独立复现/背书的支持才计入。

**定义 454（安全回归套件与晋升谓词 Promote）** `T_safe` 是**预注册、版本化、只增不减**的固定安全测试集（不变量、边界、对抗场景、不可逆屏障用例）。定义
`Promote(κ, L) = 1 ⇔ support(κ) ≥ q ∧ D(support) ≥ D_min ∧ T_safe(κ) = pass ∧ shadow(κ) ≥ n_shadow ∧ R(L) + r(κ) ≤ R_max ∧ owner(κ) ≠ ⊥ ∧ ¬creep_freeze`。
晋升是原子的：任一条件失败即整体拒绝，不存在「部分准入」。

**定义 455（影子执行与证据）** `Shadow(κ) = {(ŷ_i, y_i)}_{i=1}^{n_shadow}` 来自无执行器副本的重放/影子运行；要求成功率 `≥ n_shadow` 且 `Δ_shadow = d(ŷ, y) ≤ δ_shadow`。影子执行**不改变真实世界状态**，只产出可比较证据；沙箱内允许越出 `M_phys` 以评估候选，但该越界永远不传播到 `U_live`。

**定义 456（归属与唯一安全责任人）** 每个实时动作轨迹 `τ` 满足 `Attr(τ) = (contributors(τ), o_safe, ver)` 且 `o_safe ≠ ⊥`。`contributors(τ)` 为追溯到的贡献者集合，`o_safe` 为对该动作承担唯一安全责任的角色，拥有否决权。责任不可稀释：多贡献者不产生多头负责，只产生多头**归属**与单一**责任**。

**定义 457（贡献者分层加权共形 SCC）** `stratum = (cluster(p), ver, mode)`。对层 `s` 取加权分位 `q_s`，权重 `w_i` 校正贡献者选择偏差；要求层内覆盖
`P(Y ∈ C | s) ≥ 1 − α − TV_s`，
其中 `TV_s` 为层内与校准集的总变差漂移。若 `|C_cal^s| < n_min` ⇒ 回退第 3 轮 `SC-Cal` 全局/指令层阈值。**不能**把不同贡献者的数据直接混合做可交换假设。

**定义 458（交互预算与背压）** `load(σ) = (queue_len, recent_rate, modality_switches)`。若 `load(σ) > λ_max` ⇒ 背压：合并/延迟非关键共创提示，保留一条**安全关键优先通道**给急停、接管与不可逆警告；背压期间不得静默丢弃安全关键消息。可用 Lindley 递推刻画队列稳定性。

**定义 459（撤销证书与回滚）** `RevCert(κ) = (ver, deps, rollback, receipts)`。撤销只在 `q_quiesce` 执行；对每个 `plan ∈ deps(κ)` 重新验证 `revalidate(plan, L_{revoked})`，失败则将该计划降级为 `K=1` 或安全停机。撤销后账本回到「不含 `κ` 且依赖已重验」的状态。

**定义 460（权限蠕变检测）** `creep(t) = (ΔR/Δt, frac_live_new, rate_scope_requests)`：风险预算消耗速率、实时动作中依赖近窗口新准入技能的比例、范围扩张请求速率。若 `creep > γ` 连续 `m` 个窗口 ⇒ 冻结晋升并要求 `o_safe` 审计。由 `r(κ) ≥ r_min` 与 `R ≤ R_max` 得冻结前可扩张次数 `N_expand ≤ ⌊R_max / r_min⌋`。

**定义 461（共创作证书 CoCreationCert）** `CoCreationCert(κ) = (κ, provenance, quorum_proof, T_safe_results, shadow_stats, ΔR, owner, RevCert)`。它使一次能力扩张可被逐项审计：谁提出、谁背书、过了哪些安全测试、影子表现如何、消耗多少风险预算、谁负责、如何撤销。

**定义 462（CoGauge-8C 闭环）** `I→H→C→E→C→V→U→P`：在第 3 轮 `InstructGauge-7C` 的 `U` 之后追加 `P`（Promotion / Revocation），`P` 全异步、只在 `q_quiesce` 提交账本；实时 `I→H→C→E→C→V→U` 路径不变。

**定义 463（组合安全契约与 RepairCert″）** `RepairCert″ = (RepairCert′, CoCreationCert, Attr, RevCert)`，其中 `RepairCert′` 为第 3 轮定义 447。审计链从「贡献者 → 能力增量 → 晋升证书 → 指令/块 → 逐步回执 → 语言主张」全程可复现。

def promote(kappa, L):

## 4. 推导

**引理 59（账本固定时的实时能力闭包）** 若一个实时块执行期间账本 `L_t` 不变、且每个已准入技能都带有通过的晋升证书，则对任意实时指令 `ℓ`，`Plan_live(ℓ) ⊆ Plan(CC ∪ L_t)`；共创提交不能在块内扩大实时可行域。*证明*：由定义 450，实时通道只读 `L_t`，`U_stage` 与 `Actuator` 不连通；第 3 轮引理 51 的能力闭包论证在固定账本上逐字成立。推论：第 3 轮的块安全引理 52/56 在「相对当前账本」的意义上全部保持。

**引理 60（晋升的风险预算不变式）** 若每次晋升严格检查 `R(L) + r(κ) ≤ R_max`、`r` 非负且可加，且撤销按定义 452 返还预算，则对所有可达账本 `∀t, R(L_t) ≤ R_max`；若进一步 `r` 次可加，则任意准入集合的总风险不超过 `Σ r`。*证明*：对晋升/撤销事件归纳；晋升是唯一增加 `R` 的操作且被谓词 454 截断；撤销不增加 `R`；初始 `R(L_0) ≤ R_max`。

**引理 61（交互盾与有界接管）** 若系统在实时通道始终维护一个「可恢复态」，且 `τ_int ≤ τ_max`，则任一合法接管 `h` 在 `τ_max` 内生效，且接管过程中的轨迹仍满足 `SafeInt`。*证明*：对 `Cons` 自动机做不变式归纳；`interruptible` 保证从当前态到安全恢复态存在受控迁移；`τ_int` 给迁移时延上界；`within_authority` 与 `reversible ∨ consented` 在迁移前后保持。

**引理 62（注意力背压的稳定性）** 设安全关键消息到达率 `λ_c` 小于关键通道服务率 `μ_c`，非关键共创提示可延迟或合并，则关键通道队列稳定，且关键消息的期望积压 `E[Q_c] ≤ ρ_c/(1−ρ_c)`，`ρ_c = λ_c/μ_c < 1`。*证明*：关键通道为独立优先队列，非关键流量不抢占；Lindley 递推给出几何尾界；背压只作用于非关键提示，故不影响关键通道的稳定性。

**引理 63（贡献者分层共形的覆盖）** 若层内可交换、权重 `w_i` 正确校正贡献者选择偏差，则层内覆盖 `P(Y∈C|s) ≥ 1−α−TV_s`；若把不同贡献者数据直接混合，层内覆盖可因分布异质而远低于 `1−α`。*证明*：加权共形在可交换下给出 `1−α`；层内分布与校准分布的总变差 `TV_s` 通过标准传输不等式折损覆盖；混合池的可交换性在 `cluster` 异质时失效，给出反例（两簇均值相反、方差相同即可使池化分位系统性偏离）。

**引理 64（法定人数捕获抵抗）** 设 `n` 个贡献者中至多 `f` 个对抗，晋升要求 `support ≥ q` 且覆盖 `≥ 2f+1` 个独立簇。若 `q > f` 且簇划分满足独立性，则任何未被诚实多数背书的恶意能力无法晋升；成功投毒的失败概率由可靠性加权支持的尾界控制。*证明*：对抗者最多贡献 `f` 票；`q > f` 使其无法独立达到门槛；多样性约束阻断同一组织用多个马甲凑票；可靠性下界权重进一步压低低信誉贡献者的票值。

**引理 65（撤销等价性与回滚）** 若撤销在 `q_quiesce` 执行、且所有依赖计划都重新验证，则未受影响子图与「从未准入 `κ`」逐指令等价；任何失去有效性的依赖计划降级为 `K=1` 或安全停机，不会观察到混合账本。*证明*：`q_quiesce` 保证无在途块（第 3 轮引理 57）；账本切换是原子的；未受影响计划的证书不依赖 `κ`；失效计划按 `abort` 路径截断。

**引理 66（权限蠕变有限性）** 若每次能力扩张消耗 `r(κ) ≥ r_min > 0`、总预算 `≤ R_max`、且检测器在 `creep > γ` 时冻结晋升，则冻结前的成功扩张次数 `N_expand ≤ ⌊R_max/r_min⌋`；即权限蠕变是**有限且可检测**的，不会无限累积。*证明*：由引理 60 的风险预算单调性；每次扩张至少消耗 `r_min`；超过预算即被定义 454 拒绝；检测器提供独立于预算的早期冻结通道。

**引理 67（组合安全）** 在引理 59–66 成立时，CoGauge 的实时通道保持第 3 轮全部安全不变量；共创只能通过「认证晋升 + 静默点切换 + 可撤销账本」改变 `L_t`，故第 3 轮证明在账本参数化后继续成立。残余风险可分解为
`Risk ≤ R_max + p_capture·c_capture + p_handover·c_handover + p_shadow·c_shadow`，
其中四项分别对应预算内残余、治理捕获、接管失败与影子—现实差距。*证明*：实时通道的等价性由引理 59；预算由引理 60；接管由引理 61；捕获由引理 64；撤销由引理 65；蠕变由引理 66；四项风险通道互不掩盖，取并集界。
