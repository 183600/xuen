# 灵感循环 v3 · 第 1 轮（承接 v2）：「语音合成」×「跌倒恢复」——把动作生成重构成"语音合成"，把任务失败重构成"跌倒恢复"

> **本轮是一次"换骨架"，不是加补丁。** 承接 v2（UIP-01′~15）已核实的事实与基础设施（GSO/DRF），但用两个新灵感词重写两条主脉：**用"语音合成"重写动作生成**（吸收 v2 的 UIP-13 自适应块长、UIP-14 模块化技能图），**用"跌倒恢复"重写干扰恢复**（升级 UIP-01′/09′/12）。核心主张只有一句：**"恢复"不应是外挂的异常处理，而应是与正常技能共享同一套 token 词表、同一骨干的"另一种发音"。**

---

## 0. 承接（本轮未新增外部检索）

本轮**沿用 v2 已核实的事实（检索日期 2026-11-12）**，不在事实层重复劳动；这些事实是下面所有设计的地基：

- 排名口径 = **平均成功率 + 步骤分**；每任务计分点合计 100，**末步恒 ≥ 前序步** ⇒ 保前置、搏末步。
- `generalization.human_*` 大量是**把已完成进度反向撤回**（拧回、翻开、拉开、拿走、挪底座）⇒ **人工干扰会主动消耗你的步骤分**，而公开数据零覆盖。
- 接口 = **开环动作块**：`get_action(obs)` 返回 `action_chunk_size` 步，评测端**整块执行**后才再次调用；`reset()` 每 episode 一次；metadata 握手后不可改。
- 传输 = JPEG q95、4:4:4；堆叠帧数/分辨率直接抬延迟；N 端口并发需状态隔离；**可信度看逐步延迟及其波动 + 动作统计规律性**。
- 合规 = **单模型多任务**（外部 VLM/多模型有被判"非单模型"的风险）。

> 事实来源沿用 v2 想法区 §0（unibot 官网 `info.json`、`unibot_submission` README、HF 数据集卡片，均 2026-11-12）。本轮**不臆造新链接**；下文提到的技术族（RVQ、VQ-BeT、FAST、ACT/diffusion-policy、streaming TTS、fall-recovery）均为**方法类比**，具体文献需另行核实。

## 1. 直觉解释（先直觉，再形式化）

### 1.1 「语音合成」的直觉
说话 = **高层"说什么/什么语气"（离散、慢） + 低层"声带如何震动"（连续、快）**。TTS 的四件套正好映射到机器人：

| TTS 机制 | 直觉 | 动作侧对应 |
|---|---|---|
| 神经音频 codec（RVQ/VQ） | 把波形压成少量离散 token，重构时天然平滑 | **动作编解码 RAC**：动作块→离散 token→还原，去抖、可压缩、可组合 |
| text→mel→wave 两级生成 | 先粗后细，粗层决定"内容"，细层决定"质感" | **粗到细动作生成**：技能/阶段 token（音素）→ 粗动作 token → 细残差/连续头（波形） |
| streaming + overlap-add | 边生成边播放，接缝用交叉淡化 | **流式动作合成**：当前块执行时预生成下一块，块首做 crossfade |
| duration predictor | 预测每个音持续多久，控制节奏 | **节奏/时长规划**：预测每个计分步占多少时间，反推块长与"卡住"判据 |
| zero-shot voice cloning | 给一段参考音频，迁移未见音色 | **reference demo prompt**：给一段目标物体的短演示，迁移到未见物体/背景 |

### 1.2 「跌倒恢复」的直觉
人摔倒后**不会继续走路**，而是：**① 识别"我倒了" → ② 切到起身模式 → ③ 多策略起身（撑地/翻滚/单膝，按地形选）→ ④ 确认站稳（回到"可继续集"）→ ⑤ 重新走路**；且会判断**"这块地值不值得爬起来"**。任务级失败完全同构：

| 跌倒恢复机制 | 任务侧对应 |
|---|---|
| 跌倒检测（姿态/接触/速度） | **回归检测**：进度 Φ 下降 / 抓空 / 物体滑落 / 被 `human_*` 撤回 |
| 起身多策略 | **恢复策略阶梯**：重抓同类、换手、重定位物体、重新打开、退一步重做 |
| 回到"直立集" | 回到**可继续集**（最近一次已达成的前缀配置） |
| "值不值得爬" | **步骤分回收价值**：预估恢复能抢回多少分 vs 继续/放弃 |
| 训练靠"摔"（curriculum + 域随机化） | **造 + 挖**：DRF 造干扰 + 从现有数据挖失败段重标注 |

### 1.3 交集：一个"会说话、也会喊疼并爬起来"的动作语言模型
正常技能 = 正常语句；失败恢复 = 应激语句。**共享词表、共享骨干、共享"发音器官"（解码器）**。这样"模块化"与"单模型合规"不再冲突：恢复不是第二个模型，而是同一模型的一种生成模式。

## 2. 严谨定义（再形式化）

### 2.1 动作编解码器 RAC（Residual Action Codec）
- 编码器 $E_\phi:\mathbb{R}^{T\times d}\to\mathbb{R}^{T'\times h}$，把动作块压成隐序列 $z$。
- 残差向量量化（$L$ 层码本）：$r_0=z$；对 $\ell=1..L$：
  $c_\ell=\arg\min_k \lVert r_{\ell-1}-e_{\ell,k}\rVert_2$，$r_\ell=r_{\ell-1}-e_{\ell,c_\ell}$。
- 解码器 $D_\psi$ 以 $\sum_\ell e_{\ell,c_\ell}$（或 token 序列）为输入还原 $\hat a_{1:T}$。
- 目标：$\mathcal{L}=\lVert a-\hat a\rVert_2^2+\beta\,\mathcal{L}_{\text{commit}}+\gamma\,\mathcal{L}_{\text{smooth}}$（平滑项压低 jerk，直连"动作统计规律性"可信度）。
- **接触步保护**：对插入/合盖/拉链等子目标，允许**绕过量化**，用"token 条件 + 连续残差头"输出细动作（见 §4.3）。

### 2.2 任务进度与"任务跌倒"（Task-Fall）
- 计分步 $g_1..g_n$，权重 $w_i$（$\sum w_i=100$）；进度函数 $\Phi:S\to\{0..n\}$ 表示当前已达成的最长前缀。
- **回归/跌倒集**：$F_t=\{s_t:\Phi(s_t)<\max_{t'\le t}\Phi(s_{t'})\}$（进度被反向消耗，含 `human_*` 撤回）。
- **可继续集** $G$：从该状态起名义策略仍能推进下一计分步的状态集合。恢复的目标不是"回到初始"，而是"回到 $\Phi$ 对应的最高前缀配置"。
- **恢复 option**（semi-MDP 的 option）$O_R=(I_R,\pi_R,\beta_R)$：$I_R=F\cup\{\text{stuck}\}$；$\pi_R$ 为恢复策略；$\beta_R$ 在进入 $G$ 或预算耗尽时终止。多策略即 $\{\pi_R^{(k)}\}$ 的阶梯，按失败类型软选择。

### 2.3 步骤分回收价值（SRV）
从状态 $s$ 启动 $O_R$ 的期望得分回收：
$$Q_R(s)=\sum_{i\le\Phi^+(s)} w_i\cdot P(\text{恢复 } g_i\mid s,O_R)\;-\;\lambda\cdot\text{cost}_{\text{time}}\;-\;\mu\cdot P(\text{可信度惩罚}).$$
决策规则：**恢复当且仅当** $Q_R(s)>V_{\text{continue}}(s)+\varepsilon$ 且延迟/重做预算足够。因计分步有序、末步更值钱，恢复的靶心是 $i^\*=\arg\max$ 最近可恢复前缀。

### 2.4 流式合成与重叠相加
- 评测端执行块 $m$ 期间，策略预生成块 $m+1$；真实观测到达后只做一致性校验/纠偏。
- **块间接缝**用交叉淡化（overlap-add）：在块首 $W$ 步以 $\alpha_t$ 混合"上一块尾的延伸"与"新块"，$\alpha_t$ 取升余弦；使速度/加速度连续，降低 jerk 与接触冲击。
- 延迟分解：$T_{\text{总}}\approx T_{\text{采集}}+T_{\text{JPEG}}+T_{\text{网络}}+T_{\text{推理}}+T_{\text{执行}}$；流式的收益是把 $T_{\text{推理}}$ 藏进 $T_{\text{执行}}$，**约束**为 $T_{\text{生成}}(\text{块})\le T_a\Delta t-T_{\text{开销}}$，否则缓冲饥饿。

### 2.5 零样本"音色"迁移（reference prompt）
把一段短演示（目标物体的运动/外观）编码为参考嵌入 $u_{\text{ref}}$，动作生成条件化为 $p_\theta(c\mid o,\ell,u_{\text{ref}})$，等价于零样本 TTS 的 speaker prompt：**未见物体/背景靠"参考音色"而非重训**。

## 3. 瓶颈假设（更新）

- **H1（最高杠杆）**：接触密集步对量化误差极敏感 ⇒ 纯离散 codec 会在 T05/T09/T10/T12/T26 这类任务上掉成功率；**必须"离散打底 + 接触段连续头"混合**。
- **H2**：恢复是**有正期望步骤分**的决策，但误触发（把正常波动判成跌倒）会烧时间、烧可信度 ⇒ 需要**可校准的收益门限**与多重护栏。
- **H3**：块间硬切换的接缝抖动是隐藏杀手；流式 overlap-add 同时救**可信度**与**接触稳定性**。
- **H4**：恢复数据可"造+挖"双管齐下：DRF 脚本化造 `(干扰前→撤回→恢复)` 三元组；GSO 从现有 32 数据集里**挖失败段并重标注**。
- **H5（合规）**：codec / 恢复 / 技能头必须是**同一模型的不同模式**（共享骨干），不是外挂第二个模型。

## 1. 旗舰深潜：UIP-18 · RRS（Recovery-Native State Machine）

**直觉**：先"喊疼"（检测倒退）→ 再"起身"（多策略恢复）→ 最后"站稳再走"（回到可继续集）。**恢复是与正常技能同词表的另一种发音。**

**形式化**：见想法区 §2.2。恢复 option $O_R=(I_R,\pi_R,\beta_R)$；进入条件由进度监视器 $\Phi$ 与 SRV（UIP-19）共同决定。

**状态机**（5 态）：
`NOMINAL → (regressed/stuck) → RECOVER(strategy k) → VERIFY → NOMINAL`，任一步超预算则 `ABORT→NOMINAL(降级)`。

**关键设计**
1. **多重跌倒检测**（并联，任一触发即候选）：① 进度差分 $\Delta\Phi<0$（撤回）；② 抓取丢失（夹爪闭合但物体位移突变）；③ 长时间无进展（DPP 的时长预算超限）；④ 视觉子目标从 done 回退到 undone。
2. **起身策略阶梯**（按失败类型软选择，代价递增）：
   `S1 原地重抓 → S2 换手/换接近角 → S3 重定位物体（推到可达区）→ S4 退一步重做上一计分步 → S5 放弃并保分`。
3. **回到可继续集**：目标是最高已达成前缀 $\Phi^\*$，不是初始状态；恢复到该配置即 `RESUME`。
4. **与 01′/09′ 的差别**：v2 只检测 `regressed` 并"重做同一子目标"；v3 引入**多策略 option + 收益门限 + 预算终止**，把"重做"升级为"有策略的起身"。

```python
class RRS_Policy:                        # UIP-18 + 19 + 20 + 21 + 15
    def __init__(self, alm, monitor, dpp, srv, strategies, budget):
        self.alm, self.monitor, self.dpp, self.srv = alm, monitor, dpp, srv
        self.strategies = strategies      # [S1..S5] 起身阶梯
        self.budget = budget              # 延迟/重做/抖动预算 (UIP-15)
    def reset(self):
        self.alm.reset(); self.phi_star = 0; self.mode = "NOMINAL"
        self.k = 0; self.recover_steps = 0; self.buf = []
    def get_action(self, obs):
        phi = self.monitor.progress(obs, self.alm.lang)
        if self.mode == "NOMINAL":
            fallen, ftype = self.monitor.detect_fall(obs, phi, self.phi_star, self.dpp)
            if fallen:
                q_rec = self.srv.Q_recover(obs, self.phi_star, self.strategies)
                if q_rec > self.srv.V_continue(obs) + self.srv.eps and self.budget.ok():
                    self.mode, self.k, self.recover_steps = "RECOVER", 0, 0
        if self.mode == "RECOVER":
            self.recover_steps += 1
            if self.monitor.back_in_continue_set(obs, self.phi_star):
                self.mode = "NOMINAL"                    # 站稳
            elif self.recover_steps > self.dpp.budget_for(self.phi_star) \
                 or not self.budget.ok():
                self.k += 1                              # 下一策略
                self.recover_steps = 0
                if self.k >= len(self.strategies):
                    self.mode = "NOMINAL"                # S5: 保分降级
        prompt = self.alm.skill_prompt(self.phi_star, self.mode,
                                       self.strategies[min(self.k, len(self.strategies)-1)])
        if not self.buf:
            self.buf = self.alm.generate_chunk(obs, prompt)   # UIP-17 token 生成
        return self.scg.smooth(self.buf)                       # UIP-20 接缝平滑
```

- **可行性**：高。全部在 `get_action` 内；恢复是同一 ALM 的生成模式（改 prompt/特殊 token），不加模型。
- **资源**：靠 DRF 造恢复数据 + GSO 判分；真机只做校准。
- **风险**：误触发"疑病症" → UIP-19 门限 + UIP-15 三重预算 + `S5` 保分兜底。

## 2. 次旗舰：UIP-19 · SRV（Step-Score Reclaim Value）

**直觉**：摔倒后先判断"这块地值不值得爬起来"——因为榜单除以成功率还看**步骤分**，恢复是有 EV 的投资。

**形式化**：$Q_R(s)=\sum_{i\le\Phi^\*} w_i P(\text{recover }g_i\mid s,O_R)-\lambda\,\text{cost}-\mu\,P(\text{可信度罚})$；恢复当且仅当 $Q_R>V_{\text{continue}}+\varepsilon$。

**实现（轻量、可标定）**
- $P(\text{recover }g_i\mid s,O_R)$ 用**技能/失败类型**的查表先验初始化，再用 GSO/DRF 回放**拟合校准**（逻辑回归或小头，仍挂主干，规避多模型）。
- $V_{\text{continue}}$ = 维持当前进度并尝试下一步的期望分（含失败风险）。
- 因 $\Phi$ 有序且末步权重不降，恢复靶心取**最近可恢复前缀**，天然"保前置"。
- 每次恢复后记录 (预测 $Q_R$, 实际回收分)，滚动校准；这本身就是"可信度"证据（可解释、有日志）。

```python
def Q_recover(self, obs, phi_star, strategies):
    q = 0.0
    for i in range(1, phi_star + 1):
        p = self.p_recover(obs, i)          # 查表+校准头
        q += self.w[i] * p
    q -= self.lam * self.est_cost(obs)
    q -= self.mu  * self.est_cred_penalty(obs)
    return q
```

- **风险**：$p$ 估偏会系统性过度/不足恢复 → 强制"恢复实际回收"在线回填 + 冷启动保守门限。

## 3. 生成骨架 A：UIP-16 · RAC（Residual Action Codec）

**直觉**：像音频 codec 一样把连续动作块"压成音素"。$\hat a$ 重构天然低通，**去抖**。

**形式化**：见想法区 §2.1。训练 32 数据集全部动作流；目标含平滑项 $\mathcal{L}_{\text{smooth}}=\lVert\Delta a-\Delta\hat a\rVert$（抑制 jerk）。

**接触步保护（H1 的正面回应）**
- 两层混合解码：离散 token → 粗动作；接触密集子目标（插入/合盖/拉链/拧动）**旁路**量化，用"token 条件 + 连续残差头"输出细动作。
- 数据侧对接触段**加权重构损失**（权重 $\times 3$）。
- 验收门槛：接触段重构误差须**低于判定计分步的几何容差的一部分**，否则该步不上 codec（回退纯连续头）。

```python
class RAC:
    def encode(self, a):     return self.rvq(self.enc(a))           # -> tokens c[1..L]
    def decode(self, tokens, contact=False):
        z = self.deq(tokens)
        if contact:  return self.detok(z) + self.cont_head(z)      # 混合：离散打底+连续细化
        return self.detok(z)
```

- **风险**：码本坍塌/利用率低 → 重启码本、EMA、dead-code reset；接触段近无损须**逐任务验收**。

---

## 4. 生成骨架 B：UIP-17 · ALM（Action Language Model）

**直觉**：把"文本→语音"整条流水线搬到动作：`语言+多视角图像 → 技能/阶段 token（音素）→ 粗动作 token（mel）→ 细动作（波形）`。**恢复是一条"应激语句"。**

**特殊 token 词表**（与正常动作 token 同表）：
`<SKILL_j>`、`<PHASE_start/end>`、`<RECOVER>`、`<STRAT_k>`、`<RESUME>`、`<ABORT>`、`<EOS>`。

**训练目标**（自回归 next-token，粗到细分层）：
$$\mathcal{L}=-\sum \log p_\theta(c_t\mid c_{<t},o,\ell,u_{\text{ref}}),\quad c \in \text{按层排列的 RAC token 与特殊 token}$$
- **恢复数据格式**：`… <SKILL> 正常动作tokens <RECOVER><STRAT_k> 恢复动作tokens <RESUME> 续做tokens <EOS>`。
- **挖数据**：用 GSO 在现有 32 数据集上检测"进度回退/滑落/重试"段，重标注为 `<RECOVER>...<RESUME>`（H4）。
- **造数据**：DRF 按 `human_*` 脚本化干扰 + 示范恢复，生成三元组。
- **吸收 UIP-14**：技能图不再是外部路由表，而是模型内部的 `<SKILL>` token 序列 ⇒ 更不可能被判"多模型"。

```python
def generate_chunk(self, obs, prompt):
    toks = []
    t = self.enc_vision(obs); l = self.enc_lang(prompt); u = self.enc_ref(obs)
    while True:
        nxt = self.lm.step(t, l, u, toks)
        if nxt == "<EOS>": break
        toks.append(nxt)
    return self.rac.decode(self.split_action_tokens(toks))
```

- **风险**：自回归误差累积/复读式动作（对应 TTS 的"babble"）→ 采样温度 + 重复惩罚 + `<EOS>` 早停训练；恢复 token 误生成 → SRV 门限 + 允许"撤回恢复"回到 NOMINAL。

## 5. 生成骨架 C：UIP-20 · SCG（Streaming Chunk Generator）+ UIP-21 · DPP

### UIP-20 流式 + 重叠相加
- **边执行边生成**：执行块 $m$ 时预生成 $m+1$；观测到达后做一致性校验，必要时局部改写。
- **接缝交叉淡化**（消"咔哒"）：
  $$a_t=(1-\alpha_t)\,a_t^{\text{prev-ext}} + \alpha_t\,a_t^{\text{new}},\qquad \alpha_t=\sin^2\!\Big(\frac{\pi}{2}\frac{t}{W}\Big)$$
  因为评测端整块盲执行，**淡化在返回块内部完成**：新块以"上一块执行的末动作"为初值做 warm-start，块首 $W$ 步做衰减混合，保证速度连续。
- **产出块长约束**：metadata 只在握手声明**全局最大 $K_{\max}$**；每次可返回 $\le K_{\max}$ 步（严格按 README 形状/索引 0 先执行）。
- **延迟预算**：$T_{\text{gen}}\le T_a\Delta t-T_{\text{采集/JPEG/网络}}$，否则退化为小 $K$；与 UIP-15 共享预算。

```python
def smooth(self, buf):
    return OverlapAdd.blend(self.prev_tail, buf, W=self.w)   # 块首 W 步升余弦混合
```

### UIP-21 节奏/时长规划 DPP
- 预测每个计分步的**合理时长分布** $\hat\tau_i$（类似 duration predictor），用于：① 选块长 $K$（接触步短、搬运步长）；② **卡住判据**：实际耗时 $\gg\hat\tau_i$ 的概率尾部 → 触发 `stuck` 恢复候选；③ 给 SRV 的 `cost` 项提供时间估计。
- **风险**：时长预测偏差会误判"卡住" → 用分位数上界而非均值，且与视觉进度联合决策。

---

## 6. 泛化：UIP-22 · RVP（Reference-Voice Prompt 零样本迁移）

- **直觉**：零样本 TTS 给一段参考音色即可说新话；机器人给一段**目标物体的短演示/静态参考**即可操作未见物体、适应新背景。
- **形式化**：$p_\theta(c\mid o,\ell,u_{\text{ref}})$，$u_{\text{ref}}=f_{\text{ref}}(\text{短演示})$；与 ALM 共享编码器。
- **落地**：对未见物体（`unseen_object_*`）用同类/相似物体的 demo 作 prompt；对背景/位置变化把首帧作增强条件。
- **风险**：参考与目标分布差太大时"音色串味"（负迁移）→ 检索式参考选择 + 置信度回退到无参考模式。

---

## 7. 基础设施复用：UIP-11 GSO / UIP-12 DRF / UIP-15 CSG

- **UIP-11 GSO（判分）**：仍只作**结构/顺序代理**，不做像素级成败裁判；为 RAC 接触段容差、DPP 时长、SRV 概率提供离线真值。真机时段做锚点校准（E201/E203）。
- **UIP-12 DRF（造数据）**：按 `human_*` 生成 `(干扰前→撤回→恢复[, 策略k])` 三元组；随机化时机/速度/轨迹；输出直接喂 ALM 的恢复 token 训练。
- **UIP-15 CSG（安全阀）**：给恢复/重做/流式预生成设**延迟预算 + 抖动上限 + 最大次数**；动作平滑复用 SCG 的 overlap-add；异常即 `ABORT` 降级。

## 8. 实验设计 E201–E210（v3）

| 实验 | 对照 | 指标 | 目标（假设） |
|---|---|---|---|
| E201 | 连续回归策略 vs RAC+ALM | 成功率 / 训练样本效率 | 等效成功率下样本效率↑；接触步误差<容差 |

| E205 | 固定 k vs SCG 流式 | 延迟方差 / jerk / 成功率 | 方差↓、jerk↓、成功率不降 |

## 9. 合规、风险、时间线

### 合规
- **单模型**：RAC/ALM/RRS/RVP 全部**共享一条骨干**，恢复是同一模型的 token 模式；codec 作为模型内 tokenizer（需在提交说明中声明为同一模型的一部分，避免被判"外挂"）。
- **接口红线**：块形状 `(T_a,…)`、索引 0 先执行、返回长度 ≤ 声明 $K_{\max}$；流式淡化只在块内完成。
- **可信度**：恢复/重做/预生成一律受 UIP-15 预算约束；记录"预测回收 vs 实际回收"作可解释证据。

### 风险矩阵
| 风险 | 触发点 | 缓解 |
|---|---|---|
| 量化伤接触步 | 插网线/合盖/拧动 | 混合连续头 + 接触加权 + 逐任务无损验收 |
| 恢复误触发（疑病症） | 正常波动被当跌倒 | SRV 门限 + 分位时长 + 次数上限 + S5 保分 |
| 自回归 babbling/复读 | token 生成退化 | 温度/重复惩罚 + 早停 + 离线 GSO 过滤 |
| 流式预生成错配 | 观测与预测偏离 | 一致性校验 + 局部改写 + 超预算回退小 K |
| 仿真过拟合 | GSO 高分真机掉 | GSO 仅结构裁判 + 真机锚点 |
| 单模型合规歧义 | codec/头被视作独立模块 | 共享骨干 + 提交声明 + 单权重文件 |

### 时间线（粗排）
- 第 1–2 周：RAC 训练 + 接触段无损验收（T26/T10/T19/T16）；GSO 判据复用。
- 第 3–4 周：ALM token 生成 + 特殊 token；DRF 造恢复三元组；GSO 挖失败段。
- 第 5–6 周：RRS 状态机 + SRV 校准（E203/E204/E209）。
- 第 7–8 周：SCG 流式 + overlap-add + DPP（E205/E206/E208）。
- 第 9 周起：RVP；真机锚点校准 + 端到端 E210。

---

## 10. 本轮最大风险 & 押注

**一句话**：真正的杀手不是"生成得不够像"，而是**离散化在接触步掉成功率 + 恢复误触发烧实时性**；先用混合连续头与 GSO 逐任务无损验收证明 H1，再用 SRV 的可校准门限证明"恢复划算"，才能把"会说话也会爬起来"变成榜单上的分。

**→ 押注：UIP-18（恢复 option）× UIP-19（步骤分回收价值）** 组成的"跌倒恢复闭环"，由 UIP-17 的恢复 token 词表承载、UIP-16 的混合 codec 保证接触精度、UIP-20 的流式接缝保证可信度——它把 v2 已证实、数据全空白、且完全在选手权限内的"人为反向撤回"缺口，升级成一个**可估收益、可回填校准、可解释**的决策系统。
