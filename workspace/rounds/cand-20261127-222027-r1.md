### 第 1 轮灵感驱动研究记录（新一轮循环，承接 CADVS-v3）

**灵感词**：分层规划、隐私保护

**继承关系**：上一循环 CADVS-v3（IP-485~488）在 v2 三锚点（3DCF/Γ_3D、MSRG/S2RC、HICK/HIC）之上追加末端保真（EEK/EEC、kc_ee）与长期记忆（LTEM、kc_mem），并用联邦聚合（FFA，DP + 安全聚合）做舰队级校准，形成五硬门 EFA-v3。本轮不推翻 v3，而是在「分层规划」与「隐私保护」两个方向处理 v3 未覆盖的两个结构性问题：证书是**扁平的**（只在单条规则/单周期上判真，无法跨抽象层组合），隐私是**只护训练数据、不护证书本身**的。由此形成 CADVS-v4（IP-489~492），执行集嵌套为 Exec_CADVS-v4 ⊆ Exec_CADVS-v3 ⊆ Exec_CADVS-v2 ⊆ Exec_CADVS-v1 ⊆ Exec_v29。

**直觉与动机**：

1. **分层规划：证书必须能跨抽象层「抬升」**。真实系统不是单层规则表：任务→子任务→技能/运动基元→控制设定值，每层有自己的状态抽象与控制频率。v3 的 kc_* 只在最底层（规则/控制周期）判真；把一堆底层都通过的子技能拼成一个任务，并不能推出任务级安全——因为父层的假设（工作空间、资源、时序）可能在子层不可见，子层的保证也可能不蕴含父层的不变式。引入**分层计划证书 HPC**：计划是带层号的 DAG，每个节点带假设-保证契约 (A, G, R)，用「父假设 ⟹ 子假设、子保证 ⟹ 父保证」做契约放电，并额外检查**跨节点资源耦合的非干涉**（共享工作空间/物体/力预算）。硬门 kc_plan 只有在整棵计划树「证书闭合」时放行。

2. **隐私保护：证书本身也是侧信道**。v3 的 DP + 安全聚合只保护上传的**充分统计量**；但证书（EEC 的力/位姿、S2RC 的通过率、HIC 的手势）在跨站共享、审计、日志里会泄露操作轨迹与场景几何。攻击者收集大量低层证书即可重建轨迹（组合攻击）。引入**隐私保护证书核 PPCK**：证书以零知识证明/范围证明的形式发布，验证方只学到「谓词成立」，看不到原始力、点云、轨迹；再引入**分层隐私预算会计 HDPA**：按计划 DAG 做 RDP 组合，约束总 ε 与单次发布粒度，防止「多次低层查询拼出高层计划」。

3. **关键洞见**：安全与隐私在 v4 里共享同一个数学结构——**组合**。安全问「逐层可证的子计划能否组合成可证的计划」，隐私问「逐次低成本的发布能否组合出不泄漏的整体」。v3 的扁平门对两者都只做了「单点判定」；v4 把证书做成**可组合（contract + noninterference）且可验证而不泄露（zk + DP composition）**的对象。执行安全用六硬门，证书发布/联邦用独立治理门（kc_attest ∧ kc_privacy），两者不混用：隐私不是执行安全属性，不能拿来做急停条件。

**形式化目标（增量）**：
1. 定义分层计划 P = (V, E, ℓ)，节点契约 C_v = (A_v, G_v, R_v)，细化关系 ⊑ 与契约放电条件；定义计划门 kc_plan = 叶证据 ∧ 假设放电 ∧ 保证放电 ∧ 耦合非干涉。
2. 定义零知识证书证明 π 与 kc_attest = zk.verify(stmt, π)；定义分层 DP 会计 HDPA 与 kc_privacy = (Σ ε_RDP ≤ ε_budget) ∧ ¬singling_out。
3. 定义 EFA-v4 六硬门 kc_evidence_forged_v4 = kc_coverage ∧ kc_physics ∧ kc_human ∧ kc_ee ∧ kc_mem ∧ kc_plan；发布治理门 kc_release = kc_attest ∧ kc_privacy（不参与安全决策）。
4. 定义 Exec_CADVS-v4 ⊆ Exec_CADVS-v3：在 v3 每条路径上再要求计划级证书闭合，故只缩不涨。

**本轮最大风险**：**分层证书的组合性伪安全**——假设-保证契约是人工/自动生成且不完备的，非干涉检查只能覆盖被建模的资源耦合；未被建模的跨层耦合会让「逐层都通过」的计划在顶层联合执行时失效，而该失效对每个单层门都是不可见的。

## 2. 关键算法骨架

### IP-489 HPC：分层计划证书（计划准入/重规划，O(|V|+|E|+|R|²)）

```python
@dataclass(frozen=True)
class Contract:
    A: Callable[[State, Ctx], bool]     # 假设：入口状态/上下文
    G: Callable[[State, Ctx], bool]     # 保证：出口状态
    R: frozenset[str]                   # 资源：工作空间体素/物体 id/力预算

@dataclass
class PlanNode:
    vid: str
    layer: int                          # 0 任务 / 1 子任务 / 2 技能 / 3 控制
    contract: Contract
    children: tuple[str, ...] = ()


class HierarchicalPlanCertifier:
    """IP-489：把扁平 kc_* 抬升为计划级 kc_plan；六硬门之一，非控制环"""

    def kc_plan(self, P, x0, ctx, leaf_evidence) -> tuple[bool, str]:
        order = topo_postorder(P)                        # 子先于父
        # (1) 叶层：每个 L3 节点必须携带 v3 已通过的五门证据
        for v in order:
            if not P.nodes[v].children:
                if not self._leaf_gate(P.nodes[v], leaf_evidence):
                    return False, 'LEAF_UNPROVEN'
        # (2) 契约放电（对每个内部节点）
        for v in order:
            n = P.nodes[v]
            if not n.children:
                continue
            if not implies(n.contract.A,
                           And(*(P.nodes[c].contract.A for c in n.children))):
                return False, 'ASSUMPTION_GAP'
            if not implies(And(*(P.nodes[c].contract.G for c in n.children)),
                           n.contract.G):
                return False, 'GUARANTEE_GAP'
        # (3) 资源耦合非干涉（v3 完全没有这一项）
        if not self._noninterference(P):
            return False, 'CROSS_COUPLING'
        return True, 'PLAN_CLOSED'

    def _noninterference(self, P) -> bool:
        """冲突图 Conf(P) 的每条边必须被互斥/时序守卫 M_{uw} 覆盖。
        这是「逐层都通过、联合却失效」的唯一拦截点。"""
        for (u, w) in self._conflict_edges(P):
            if not self._has_guard(u, w):       # 串行化或联合不变式（如 Σf≤F_max）
                return False
        return True
```

### IP-490 PPCK：隐私保护证书核（发布/审计时，非控制环）

```python
@dataclass
class Attestation:
    stmt: str            # 谓词真值声明（不含原值）
    proof: bytes         # zk-SNARK / 范围证明
    commitment: bytes    # 对证书载荷的承诺（隐藏力/位姿/点云）


class PrivacyPreservingCertificateKernel:
    """IP-490：跨站/跨层只验证谓词，不见原始力、点云、轨迹"""

    def prove(self, stmt: str, witness: dict) -> Attestation:
        """witness 含 f_contact/p_ee/δ_pose 等；生成后原值不离开本地"""
        commitment = pedersen_commit(witness)
        proof = zk.prove(stmt, witness, commitment)
        return Attestation(stmt, proof, commitment)

    def kc_attest(self, att: Attestation) -> bool:
        """完备性：真陈述必过；可靠性：伪陈述以可忽略概率被接受；零知识：只暴露 stmt"""
        return zk.verify(att.stmt, att.proof, att.commitment) == 1
```

### IP-491 HDPA：分层隐私预算会计（发布前，非控制环）

```python
class HierarchicalPrivacyAccountant:
    """IP-491：按计划 DAG 做 RDP 组合；总预算 + 单次发布粒度约束"""

    def __init__(self, eps_budget: float, delta: float, alpha: float = 8.0):
        self.eps_budget = eps_budget
        self.delta = delta
        self.alpha = alpha
        self.ledger: dict[str, tuple[float, float]] = {}   # node -> (eps_r, delta_r)

    def charge(self, node_id: str, eps_r: float, delta_r: float) -> None:
        self.ledger[node_id] = (eps_r, delta_r)

    def total_rdp(self) -> float:
        return sum(eps_r for eps_r, _ in self.ledger.values())   # RDP 组合可加

    def kc_privacy(self, P) -> tuple[bool, str]:
        if self.total_rdp() > self.eps_budget:
            return False, 'BUDGET_EXHAUSTED'
        if self._singles_out(P):        # 任一发布粒度 < g_min，或跨层唯一可识别
            return False, 'SINGLING_OUT'
        return True, 'PRIVATE'
```

### IP-492 EFA-v4：六硬门 + 独立发布治理门

```python
class EvidenceForgingAssemblerV4:
    """EFA-v4：执行安全六硬门 fail-closed；隐私/证明是发布治理门，不混作急停"""

    def hard_gate(self, x, t_now, rule_id, hic, eec, plan,
                  leaf_evidence, ctx) -> tuple[bool, str]:
        ok, why = self._v3_hard_gate(x, t_now, rule_id, hic, eec, ctx)
        if not ok:
            return False, why                       # 继承五门
        ok_plan, why_plan = self.hpc.kc_plan(plan, x, ctx, leaf_evidence)
        if not ok_plan:
            return False, why_plan                  # 新增计划门
        return True, 'FORGED_V4'

    def release_gate(self, att, plan) -> tuple[bool, str]:
        """证书对外/跨站发布前的治理门（不影响执行安全）"""
        if not self.ppck.kc_attest(att):
            return False, 'ATTEST_INVALID'
        if not self.hdpa.kc_privacy(plan):
            return False, 'PRIVACY_BREACH'
        return True, 'RELEASABLE'
```

```
      ├─ ASSUMPTION_GAP  → 收紧子任务前置条件 / 重新分解
      ├─ GUARANTEE_GAP   → 加中间不变式 / 降级子技能

  每周期：EEK 读力/力矩/触觉 → EEC → kc_ee

      ├─ HIC_STOP / COVERAGE_BLIND / PHYSICS_UNPROVEN / EE_UNPROVEN / MEMORY_REJECT → v3 回退

  EEC/S2RC/HIC ──▶ PPCK.prove ──▶ Attestation
  计划级发布 ──▶ HDPA.charge ──▶ EFA-v4.release_gate ──▶ 跨站共享/FFA 上传

```

## 4. 正确性论证（增量更新）

### 引理 41（契约放电的归纳可靠性）

**陈述**：若计划 P 的每个叶节点在其假设成立时其保证成立，且每个内部节点 v 满足 discharge(v)（A_v ⟹ ⋀ A_c，(⋀ G_c) ⟹ G_v），则对任意与叶层假设一致的执行，根节点保证 G_root 成立。

**证明**：对 DAG 的拓扑逆序归纳。叶层由前提直接得 G_leaf。设子节点保证均成立，则 ⋀ G_c 成立，由 discharge 的第二式得 G_v；同时由第一式，父假设沿细化向下传递，保证子层前提不被违反。归纳至根。∎

### 引理 42（跨耦合不可省略——非干涉是必要的）

**陈述**：存在计划 P，其所有叶证据通过、所有父子契约放电成立，但联合执行违反某安全不变式；故 kc_plan 必须显式检查非干涉。

**证明（构造）**：两机械臂对同一物体各施加 f ≤ F_max，各自契约 A_i =「臂 i 单独作业」、G_i =「接触力 ≤ F_max」、R_i = {物体 o}。父子放电仅用单臂保证，无法推出父契约 G =「物体受力 ≤ F_max」；实际联合力为 2F_max 时可压碎物体。另例：两子任务各自无碰撞，但工作空间体素重叠，联合执行相撞。两例中逐层门全部通过而联合不安全，故必须由 Conf(P) 上的守卫 M 显式拦截。∎

**工程含义**：v4 相对 v3 的实质增量不是「又加一个门」，而是把**组合**本身证书化；单层门的合取在数学上推不出计划级安全。

### 引理 43（零知识证书的可靠性与隐私边界）

**陈述**：若 zk 方案满足完备性、计算可靠性与零知识性，则 kc_attest 通过意味着 stmt 为真（以可忽略可靠性误差），且验证方除 stmt 外不获得 witness 的信息。**但**：stmt 只约束「被承诺的传感器读数满足谓词」，不保证读数本身物理真实。

**证明**：由 SNARK 的完备性/可靠性与零知识定义直接得。物理真实性需额外假设：witness 由可信传感器根（TEE/签名传感器）产生。∎

**工程含义**：隐私层不能替代物理锚；它是「读数的可验证封装」，不是「读数真实性」的来源（见 R47）。

### 引理 44（分层 DP 组合与预算门）

**陈述**：若计划内每次发布为 (α, ε_r)-RDP，则整个计划为 (α, Σ ε_r)-RDP；再由标准转换得 (ε, δ)-DP，其中 ε = Σ ε_r + log(1/δ)/(α−1)。kc_privacy 通过即保证总泄漏不超过 ε_budget，且 g_min 约束排除单次发布对个体的唯一识别。

**证明**：RDP 的组合可加性是 Rényi 散度的链式法则直接结论；RDP→DP 转换为标准结果。∎

**工程含义**：把「隐私预算」从单次查询的局部约束提升为整棵计划树的全局约束，封堵「多次低层低成本查询重建高层轨迹」的组合攻击。

### 定理 v4（执行集收缩、计划组合可靠、隐私可控）

**陈述**：在以下假设下：(B1) 契约 (A,G,R) 对真实耦合完备；(B2) 叶证据忠实（继承 v3 的 B1–B4）；(B3) zk 方案可靠且 witness 由可信传感器根产生；(B4) DP 机制与 RDP 组合成立。则：
(i) Exec_CADVS-v4 ⊆ Exec_CADVS-v3 ⊆ … ⊆ Exec_v29（严格收缩）；
(ii) kc_plan 通过 ⟹ 根保证在任意与叶假设一致的执行下成立（引理 41），且无未守卫的资源冲突（引理 42）；
(iii) 发布满足 (ε_budget, δ)-DP 且不 singling-out（引理 44）；
(iv) 六硬门 fail-closed，仅 HIC veto 旁路至 S_stop；发布治理门与安全门解耦。

**证明**：(i) v4 在 v3 每条路径上追加 kc_plan（计划准入/重规划），故只缩不涨；严格性由 v3 无法检出、而引理 42 构造的「逐层通过但联合失效」计划被关闭保证。(ii) 引理 41 + 42。(iii) 引理 44。(iv) 由 EFA-v4 的合取结构与 release_gate/hard_gate 分离直接得。∎

**诚实声明**：(B1) 是本轮最脆弱假设——契约由人工模板或 LLM 生成，非干涉只覆盖被建模的资源；未建模耦合（热、磨损、通信延迟、共享电源）不在 Conf(P) 内，因此「计划闭合」是相对于**当前契约语言**的可靠性，不是绝对安全。缓解：契约库版本化 + 反例回灌 + 未建模耦合登记表 + 高风险计划强制人审。

## 7. 本轮最大风险（最终确认）

**一句话**：**分层证书的组合性伪安全**——假设-保证契约与资源非干涉只能覆盖被建模的耦合，未被建模的跨层耦合会让「逐层都通过」的计划在顶层联合执行时失效，且该失效对每个单层门都不可见；而为了压住隐私预算而复用/粗化低层证书，恰好会抹掉发现这种耦合所需的细节，使安全与隐私在组合处同时失守。
