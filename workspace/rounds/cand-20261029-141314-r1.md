# 第 13 轮 · STANCE-VIEW SEARCH：演示给的是「任务级静态 stance 先验」，不是连续全身策略；泛化时在安全集内重选视角与可达域

> 检索/复核日期：**2026-10-29（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是灵感循环第 1 轮，三个词是「数据标注」「视觉感知」「平衡控制」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是给它们补一个更慢的身体环：**CHUNK-SERVO 解决最后 3 厘米；SVS 解决「目标被挪走后，身体还站在旧位置」的 30 厘米和 30°。**

## 0. 先给结论：真正的缺口不是「再学一个全身策略」，而是「演示 stance 先验在泛化时失效」

截至 2026-10-29，官网榜单仍是 8 个模型：MolmoAct 29.7%、WALLOSS 28.5%、DreamZero 27.9%、Spirit 25.9%、DM 23.5%、PI 22.8%、GigaBrain 22.6%、GR00T 20.5%。头尾差 9.2pp。榜单详情页仍是「测试视频占位」；运行页 256 条记录里，单任务成功率出现 25.1%、32.7%、38.2% 等非 10% 整数倍——每个任务只有 10 次 trial，真实成功率只能是 k/10。所以这些数字只能当「预览/难度信号」，不能当实测 SOTA 或任务难度表。

但这一轮我抓到一个比榜单更硬、也更容易被忽略的事实：**官方 WLA 的 action server 明确把 challenge 的 7 维 `action.pivot` 定义为 `[vx, vy, vw, yaw, pitch, roll, height]`，其中 yaw/pitch/roll 来自 waist（`lower_body` 最后 3 维，原顺序是 yaw,roll,pitch），height 来自 base_command。** 代码里甚至写清楚了重排：`yaw=waist[0]`、`pitch=waist[2]`、`roll=waist[1]`。也就是说，pivot 不是「底座速度」这么简单，它是 **3 自由度腰 + 身高 + 底座速度** 的混合接口。G1 的头相机固定在躯干上，腰 pitch 与头相机 pitch 在抽样数据里相关系数 1.000；腰 yaw/pitch/height 直接决定「看哪里、看多高、够不够得着」。

我一开始用 min/max 看 33k 演示，得到腰 yaw 最大 0.876 rad（50.2°，OrganizeTools）、height 最大变化 0.132 m（PickOutBatteries），很容易得出「演示大量使用 stance，应该做一个连续全身控制器」。但把 32 个任务的 q01/q99 和 q10/q90 拉出来后，结论相反：

- **height 的 q10–q90 在所有任务都 ≤0.0001 m**，q01–q99 最大也只有 0.0001 m；height 基本是任务级常数。
- **waist yaw 的 q10–q90 最大 0.087 rad（5.0°）**，q01–q99 最大 0.132 rad（7.6°）。
- **waist pitch 的 q10–q90 最大 0.145 rad（8.3°）**，q01–q99 最大 0.246 rad（14.1°）。
- min/max 的大值集中在 1–2% 尾部，可能是 reset/首尾过渡/少数动态帧；不能当作持续行为。

所以：**演示是「任务级静态 stance + 小幅腰 pitch 调整」，不是连续 stance 伺服。** 这个修正很重要：它把方案从「从演示学一个全身动态策略」改成「用演示做安全先验，在泛化时事件触发重选」。前者数据不够、风险大；后者数据刚好够、风险可控。

这正好对上挑战赛的 5 类泛化：位置变化、干扰物、背景变化、未见物品、人为干扰。演示是在成功、摆好的场景里采的，所以它们的 stance 先验是「对 demo 布局最优」，不是「对任意布局最优」。当物体被挪远、挪低、被遮挡，或被人类移动时，头相机可能看不到目标，手臂可能够不到；这时缺的不是语义，而是 **在安全 stance 集内重新选一个「看得见、够得着、不会破坏接触」的身体位置**。

一句话押注：**把 G1 的 7 维 pivot 当成「任务级静态 stance 先验 + 事件触发的安全集重选」接口；演示给出安全 stance 集，泛化导致目标出视野/超可达域时，在安全集内搜索一个新的 stance，慢速切换后再交给 CHUNK-SERVO 闭环。**

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **数据标注** | BODY-LABEL：从 33k 演示自动标注任务级 stance 先验/安全集、view/reach、phase、contact、reliability；把线上拿不到的 `state_d435`/`state_torso`/`ee_pose_gripper_torso` 作为特权标签，蒸馏成线上可观测的映射 | 不手工标 33k；不把标注当第二个在线模型；不把 min/max 当持续行为 |
| **视觉感知** | VIEW-MEM：头双目米制深度 + 3D 目标记忆；stance 改变后重投影/重定位；腕部近距更新；visibility/reach 作为 stance 搜索的效用 | 不做纯 6D 位姿网络；不依赖 depth/force/tactile；不假设腕部有内参 |
| **平衡控制** | 安全 stance 集 + CoM/支撑多边形代理 + 速率限制 + 接触段冻结；WBC 负责底层平衡 | 不做全身 RL；不移动 base；不在接触段变 stance；不把 demo 尾部当安全区 |

## 1. 本轮新核实的事实

### 1.1 榜单/运行页：仍是预览，不是实测

- 官网首页/榜单（2026-10-29）8 个模型，最高 29.7%、最低 20.5%，与第 12 轮一致。
- `runs.html` 有 256 条记录，但单任务成功率出现 25.1%、32.7%、38.2%、32.1%、20.9%、29.9%、24.9%、25.9% 等非 10% 整数倍；规则是每任务 10 次，真实成功率只能是 k/10。这说明运行页不是最终实测数据，可能是预览、合成或跨更多 trial 的聚合。
- `details.html` 的视频仍是「测试视频占位，后续可替换为真实视频文件」。
- 结论：**榜单只能用来判断「头部大约 30%、尾部大约 20%」和「模型清单」，不能用来排任务难度或估计某个模型的真实任务级成功率。** 任务优先级必须用单任务不计分通道自己测。

### 1.2 pivot 的真实语义：3 自由度腰 + 身高 + 底座速度（A）

官方 `unifolm-wla` 的 `action_server_wbc_msgpack_unitree.py`（2026-10-29 复核）在文件头写明：

```text
action.pivot (1, T, 7)  vx, vy, vw, yaw, pitch, roll, height
    vx/vy/vw/height are the same 4 values as base_command; yaw/pitch/roll
    come from the waist (lower_body last 3, ordered yaw,roll,pitch) remapped
    into pivot's yaw,pitch,roll order.
```

构造代码也写得很清楚：

```python
# pivot = [vx, vy, vw, yaw, pitch, roll, height]. The waist (lower_body
# last 3) is ordered [yaw, roll, pitch], so remap: yaw=waist[0],
# pitch=waist[2], roll=waist[1].
waist = unnorm[:, SLICES["waist_joint"]]    # (T,3) = [yaw, roll, pitch]
pivot = np.concatenate([
    vx_vy, vw,
    waist[:, 0:1],   # yaw
    waist[:, 2:3],   # pitch
    waist[:, 1:2],   # roll
    height,
], axis=1).astype(np.float32)               # (T,7)
```

这给出四个直接推论：

1. **pivot 不是「底座命令」的同义词。** 它把腰 yaw/pitch/roll、身高和底座速度打包在一起；只输出 `[vx,vy,vw,0,0,0,0]` 等于把腰和身高都设成零，不是「保持当前姿态」。
2. **pitch/roll 顺序是陷阱。** 数据集 waist 是 `[yaw, roll, pitch]`，pivot 是 `[yaw, pitch, roll]`。如果把 `lower_body[-3:]` 原样塞进 `pivot[3:6]`，pitch 和 roll 会互换；机器人可能「想前倾却侧倾」，头相机视角也跟着错。这个 bug 在真机上很难从日志看出来，必须在 G0 用 +0.1 rad pitch / +0.1 rad roll 分别验证。
3. **height=0 不是中性值。** 演示的 height 均值约 0.737 m（跨任务 0.7273–0.7400 m），零动作的 height=0 远低于此。官方 example policy 返回零动作只是 stub；如果直接拿零 pivot 当 baseline，可能一上来就蹲下/被限幅，成功率和安全性都不可信。
4. **HF 数据集的 `action.pivot` 不是 challenge pivot。** HangCup 的 HF `action.pivot` 是 `[0,0,0,0,0.15,0,0.74]`，而同一帧的 waist 是 `[-0.01,-0.0037,0.1806]`；OrganizeTools 的 `action.pivot[3]/[4]` 的 std 是 0.147/0.118，而 waist yaw/pitch 的 std 是 0.075/0.093。**不要用 HF 的 `action.pivot[3:6]` 当 waist 标签**；用 `action.waist_action_joint` / `lower_body[-3:]` + `action.base_command` 按 WLA server 的映射重建。

**证据等级**：WLA action server 的 pivot 定义是 A（官方代码）；「挑战赛评测端使用同一语义」是 C，需要在单任务通道用小幅 waist/height 指令验证。验证方法见 §3.6。

读法：

- **height 在任务内几乎是常数。** 32 个任务的 height q10–q90 都 ≤0.0001 m；跨任务均值也只差 1.27 cm。演示没有「蹲下/站起」的持续动作，只有一个任务级高度先验。
- **waist pitch 有小幅任务内调整，但不大。** 最大的 OrganizeTools 也只有 q10–q90 = 0.145 rad（8.3°），q01–q99 = 0.246 rad（14.1°）；其他任务大多 <0.02 rad。

- **任务间差异是「小偏移」，不是「大动作」。** 32 个任务的任务均值：height 0.7273–0.7400 m，waist pitch 0.1264–0.2394 rad（7.2–13.7°），yaw 均值 −0.0182 rad，roll 均值 −0.0174 rad。也就是说，一个任务级 lookup table 就能覆盖大部分 stance 先验。
- **min/max 的尾部不能当安全区。** 例如 PickOutBatteries 的 height min 0.608 m、max 0.740 m，但 q01–q99 是 0.7295–0.7295 m；如果按 min/max 设计「蹲到 0.61 m」，就跳出了演示安全区。

这个修正直接改变了方案的重心：**不是学连续全身策略，而是学/查任务级 stance 先验，再用事件触发的安全集搜索处理泛化。** 前者需要大量动态全身数据（我们没有），后者只需要 33k 成功演示的分布 + 一个小候选集 + 在线可见性/可达性评估。

### 1.4 身体-视角耦合：腰 pitch 就是头相机 pitch（B）

在 HangCup、OrganizeTools、StorePaddle、PickOutBatteries、FoldTowel 五个任务各抽 600 帧（2026-10-29 分析）：

- `waist_state_joint[2]`（pitch）与 `state_d435` 的 pitch 相关系数 **1.000**。头相机 pitch 可以视为腰 pitch 的刚性映射；腰 pitch 变 1°，头相机 pitch 也变约 1°。
- `action.pivot.height` 与膝角/相机高度的相关性随任务变化：HangCup 0.84、OrganizeTools −0.29、StorePaddle −0.74、PickOutBatteries −0.53、FoldTowel 0.37。**不能用统一的「height=膝角」线性模型**；height 是 WBC 命令，映射依赖任务/腿型/接触。安全做法是用演示分布做安全集，而不是用膝角反推。
- 头双目已校正：基线 **58.2526 mm**，HangCup 的 `fx≈282.37`，`rectified: true`；腕部相机只有 `color/ir1/ir2`，**没有内参矩阵**。

这意味着：**stance 是视角的慢速控制器，但不是连续云台。** 一个 5–8° 的腰 pitch 变化足以把低处/远处目标从画面边缘拉回中心；一个 5° 的 yaw 变化足以绕过轻度遮挡。对桌面任务，这比让手臂去「够到画面外」更安全。

### 1.5 G1 形态与 API 约束：短臂 + 固定头 + 无深度/力（A）

- G1 高约 1.32 m、重约 35 kg；官方参数页给的手臂工作半径约 0.45 m、腿长约 0.6 m。桌面任务的目标常在身前 0.4–0.8 m、高度 0.7–1.1 m；短臂 + 固定头意味着 **身体位置直接决定「能不能够到」和「能不能看到」**。
- API 只有四路 RGB 480×640；没有 depth、camera_info、force/torque、tactile。头双目是唯一米制深度来源；腕部只能做 2D 对齐或一次性标定后的近距更新。
- 动作侧 `control_space` 只能二选一：`joint` 或 `ee`；`action.pivot [7]` 共用；`action_chunk_size` 固定。官方 WLA 的 chunk 是 30 步 @30Hz（约 1 s），chunk 内没有新观测。这保留了第 12 轮 CHUNK-SERVO 的结论：**执行层必须把 30 步切成更短的闭环块。**
- 单模型规则：所有任务须同一模型；不能为每个任务训一个策略。SVS 的 planner 是确定性搜索/控制器，BODY-LABEL 是离线标注，lookup table 是配置表——都不是第二个在线学习模型。合规论证见 §3.7。

### 1.6 相关工作：全身 VLA、自动标注、手眼标定都在升温，但没人把「stance 先验 + 安全集重选」接到这个挑战赛

**全身 VLA（说明「身体重要」，但大多假设动态全身数据/训练）：**

- **OpenHLM**（arXiv 2606.22174，2026-06-20）用 35-DoF 人形，把任务指令和像素级控制放在同一序列里做长程操作，强调「whole-body」而不是「arm-only」。
- **MotionWAM**（arXiv 2606.09215，2026-06-08）单阶段 whole-body world-action model，报告在长程原子任务上相对基线 **30%+** 提升；说明身体动作与操作动作联合建模有收益。
- **HAF**（arXiv 2608.16837，2026-08-17）层次化 action feedback，解决长程人形操作中的执行偏差。
- **WholeBodyVLA**（arXiv 2512.11047，2025-12-11）用统一 latent 做 locomotion-manipulation，强调移动与操作联合。
- **Holo-M**（arXiv 2609.35709，2026-09-28）层次化 VLA，在 Jetson Thor 上做到 0.29 s 级响应；说明全身 VLA 可以进实时。
- **HumanoidVLA**（arXiv 2601.14874，2026）把 CoM 等平衡信号注入 VLA，说明「平衡感知」可以影响操作策略。

这些工作支持「身体不是固定三脚架」的方向，但它们大多需要动态全身演示/强化学习；本挑战赛的 33k 演示是静态 stance，直接套完整全身 VLA 会数据不足。我们只借「身体-视角-平衡耦合」的洞察，不借它们的训练配方。

**自动标注（说明「特权信号 → 标签」可行）：**

- **SPARC**（arXiv 2606.13497，2026-06）用空间标注提升 VLM 规划的空间推理。
- **RoboInter**（arXiv 2602.09973，2026-02-10）做交互式中间表示标注，提升数据效率。
- **FineART**（arXiv 2609.36416，2026-10-05）做细粒度操作标注。
- **YUBI-STAG**（arXiv 2610.09718，2026-10-07）做时空 affordance 标注。
- **Grounded in Time**（arXiv 2610.04255，2026-10-03）做时序 grounding。
- **VLA-Δ**（arXiv 2610.21306，2026-10-15）用动作变化检测做关键片段标注。
- **Automatic Labelling for Bimanual Mobile Manipulation**（arXiv 2609.24059，2026-09）直接用自动标注做双臂移动操作。

这些工作证明「不用手工标，也能得到可用标签」；但没人针对 G1 桌面任务标 **stance prior / safe set / view quality / reach margin / phase**。这正是 BODY-LABEL 的空白。

**手眼标定（说明腕部无内参不是绝路）：**

- **CalibAll**（arXiv 2511.17001，2025-11）在未知相机位姿下做联合标定。
- **Bi-JCR**（arXiv 2505.24819，2025-05）做联合相机-机器人标定，适合腕部相机。
- **Kalib**（arXiv 2408.10562，2024-08）是经典多相机标定工具箱；**Hydra**（arXiv 2504.20584，2025-04）做无标定手眼。
- 本方案不把腕部标定当主创新；只在需要近距米制更新时用一次棋盘格/演示自标定，失败就退回 2D 对齐。

**平衡/接触（说明 CoM/支撑多边形可做代理，但不必自己训 RL）：**

- **DreamControl**（2026）用 CoM-aware 世界模型做人形平衡；**ULC**（arXiv 2507.06905，2025-07）用对抗运动先验做通用人形控制；**BAT**（arXiv 2604.01064，2026-04）做平衡感知的全身跟踪；**PILOT**（arXiv 2601.17440，2026-01）做触觉/平衡容错。
- 这些是动态全身控制；本方案只用它们的 **CoM/支撑多边形指标** 做候选排序，底层平衡仍交给官方 WBC。

**空白**：没有工作把「任务级静态 stance 先验（来自 33k 成功演示）+ 事件触发的安全集 stance 搜索 + 头双目视角评估 + CHUNK-SERVO」组合到 UniBot 挑战赛。这个空白不是「再训一个更大的 VLA」，而是「把已有的身体接口用对」。

## 2. 诊断：三个「固定」导致三个泛化失败

### 2.1 固定 stance → 目标一挪，视野/可达域就出界

演示的 height 在任务内几乎不变，waist pitch 也只有小幅调整。这说明策略很可能学到一个「任务平均 stance」，然后在整个 episode 里保持。问题在于：

- 位置泛化把目标挪远 10–20 cm，手臂可能进入伸展极限；如果身体不跟着前倾/降高，末端姿态会变得别扭，夹爪对准误差放大。
- 目标挪低（桌面边缘/盒子里）时，固定头相机可能看不到目标；手腕相机虽然近，但看不到「目标-容器」的整体关系。
- 目标挪到侧面时，固定腰 yaw 会让头相机视野偏心；手腕相机也未必覆盖。

**需要的不是连续全身策略，而是一个「换一个任务级 stance」的离散选择。** 因为演示本身告诉我们：任务级 stance 是稳定的、可查的；变化应该是事件触发、慢速、有限的。

### 2.2 固定视角 → 遮挡/透明/人为干扰时，VLA 看到的是错的世界

API 没有深度，头双目是唯一米制来源；腕部无内参。透明容器、反光桌面、人手遮挡会让头双目深度出现空洞，VLA 的 2D 语义可能仍然「自信」，但 3D 位置已经漂移。固定的头相机视角无法通过「换个角度看」来消歧；而腰 yaw/pitch 的小幅变化可以产生**视差**，让透明边缘/遮挡关系变得可解。

**VIEW-MEM 的作用**不是做 SLAM，而是：记住目标在 base 系的大致 3D 位置； stance 改变后重投影；如果目标仍可见就更新，不可见就用记忆 + 腕部近距；如果记忆过期就触发一次小范围 stance 搜索（左看/右看/前倾），而不是让手臂盲抓。

### 2.3 固定接触时序 → 在错误的时候动身体，会把接触破坏

桌面任务里，很多失败不是「没够到」，而是「够到了但碰倒了/推走了/夹歪了」。如果在接触段改变 height/waist，末端会跟着躯干动，接触力/位置突变，容易把物体推走。**SVS 的关键约束是：stance 只在 approach/transport/recover 段变；align/contact/release 段冻结。** 这和 CHUNK-SERVO 的接触检测复用同一套信号（夹爪开度、EE 速度、目标距离、视觉接触）。

## 3. 方法：SVS（Stance-View Search）

### 3.1 三频 + 事件触发：stance 不是一直动，而是「该动才动」

```text
慢环  Stance Prior / Search     事件触发，候选评估 20–50 ms，切换 0.5–1.0 s
中环  VLA plan                  ~1 Hz，30 步 chunk（官方 WLA）
快环  CHUNK-SERVO               6.7 Hz，5 步执行块 + 视觉修正
```

- **默认不动**：每个 episode 开始时，用语言指令查任务级 stance 先验 `s_prior`，直接作为 pivot 的 yaw/pitch/roll/height；`vx=vy=vw=0`。
- **触发条件**（满足任一，且 phase 不在 contact/align/release）：
  - 头双目中目标可见比例 `V(s_current) < 0.6`；
  - 目标到肩部的工作空间裕度 `R(s_current) < 0.15`；
  - VLA/CHUNK-SERVO 的置信度低于阈值（例如目标重投影误差 > 15 px 持续 3 帧）；
  - 检测到人为干扰/目标被移动（目标 3D 位置突变 > 3 cm，或可见性骤降）。
- **搜索**：在 `s_prior` 周围的小候选集里评估 `V(s)`、`R(s)`、`B(s)`，选一个；只执行一次，然后重新观测。若没有候选显著优于当前，保持不动，交给 CHUNK-SERVO/重规划。
- **为什么事件触发**：演示的 stance 是静态的，连续动身体既没有数据支持，也会增加摔倒/破坏接触的风险。事件触发把「身体动作」限制在真正需要的少数时刻。

### 3.2 BODY-LABEL：从 33k 演示自动标注「先验 + 安全集 + 视角/可达/阶段」

BODY-LABEL 不是一个在线模型，而是一个离线标注管线；输出三类标签：

1. **任务级 stance 先验与安全集**
   - 对每个任务，统计 `height`、`waist yaw/pitch/roll` 的均值、q01/q99、q10/q90、std。
   - `s_prior(task) = [yaw_mean, pitch_mean, roll_mean, height_mean]`。
   - `S_task = [q01, q99]` 作为硬安全框；工程上再留小余量（height ±0.02 m、pitch ±0.08 rad、yaw ±0.08 rad），但**不进入 min/max 尾部**。
   - 线上通过语言指令模糊匹配任务名；匹配失败用全局先验 `[0, 0.172, 0, 0.737]`。
2. **帧级 view/reach/phase 标签**
   - `V_t`：目标点云在头双目中的可见比例 + 居中程度 + 深度有效比例。
   - `R_t`：目标到肩部/臂展的工作空间裕度（用 URDF 和 `state_torso`/`waist_state_joint` 算）。
   - `phase_t`：从夹爪开度、EE 速度、目标距离、`action.gripper_controls` 自动切分为 approach/align/contact/transport/release/recover。
   - `contact_t`：夹爪闭合 + EE 速度下降 + 目标距离稳定；离线可用 `gripper_controls` 监督。
3. **特权字段 → 线上可观测映射**
   - 离线有 `state_d435`、`state_torso`、`ee_pose_gripper_torso`、`recomputed_ee_valid`；线上只有 `lower_body` + EE base + 四路图。
   - 用离线数据拟合 `T_base_d435 = f(waist)`（刚体变换），线上用 `lower_body[-3:]` 恢复头相机位姿；用 `T_base_torso = f(waist)` 恢复躯干系，进而把 EE base 转到 torso 系做 reach。
   - `recomputed_ee_valid` 在 32 任务全为 1.0（我们已核对），说明演示的 EE 标签质量高；仍保留过滤逻辑。

**BODY-LABEL 的产物**不是一个大模型，而是：每任务 4 个数（stance 先验）+ 每任务 8 个数（安全框）+ 一个头相机外参映射 + 一个 phase 分类器（可用简单阈值/逻辑回归；若用学习模型，只训练期/辅助头，不作为第二个在线策略）。

### 3.3 stance 搜索：小候选集 + 可解释效用 + 硬安全约束

候选集（默认 27 个 + 当前）：

```text
yaw   ∈ {yaw_prior − 0.08, yaw_prior, yaw_prior + 0.08}      # ±4.6°
pitch ∈ {pitch_prior − 0.08, pitch_prior, pitch_prior + 0.08}
height∈ {height_prior − 0.02, height_prior, height_prior + 0.02}
```

每个候选 `s` 评估：

- **可见性** `V(s)`：把目标点云 `P_t` 用候选头相机位姿投影到头双目；可见比例 × 居中程度 × 深度有效比例。目标点云来自头双目 + 2D 分割（Grounded SAM 2/颜色/尺寸先验），不训练新网络。
- **可达性** `R(s)`：目标到肩部的工作空间裕度；`R = clip(1 − ||p_target − p_shoulder(s)|| / L_arm, 0, 1)`。`L_arm` 用 URDF，不用「臂展 0.45 m」的粗略值。
- **平衡代理** `B(s)`：优先用 `s` 与 `s_prior` 的标准化距离（因为演示安全框已经是平衡证书）；如果仿真/URDF 可算 CoM，再用 CoM 到支撑多边形边缘的距离做二次排序。**不要用未标定的 CoM 硬拒候选**；硬拒只靠 `s ∈ S_task` + 速率限制 + 接触冻结。
- **切换代价** `D(s)`：`||s − s_current||`，避免为了 1% 可见性提升做大动作。

效用：

```text
U(s) = w_v V(s) + w_r R(s) − w_b B(s) − w_d D(s) − w_p ||s − s_prior||²
s.t.  s ∈ S_task,  |Δheight| ≤ 0.02 m/s, |Δwaist| ≤ 0.3 rad/s,
      phase ∉ {align, contact, release},  vx=vy=vw=0
```

- 权重 `w_*` 先在仿真/单任务网格搜索，不学习；默认 `w_v=1.0, w_r=1.0, w_b=0.5, w_d=0.3, w_p=0.2`。
- 如果 `max_s U(s) − U(s_current) < 0.05`，不切换；避免抖动。
- 切换用 0.5–1.0 s 的 smoothstep 插值；切换期间冻结手臂目标/让 CHUNK-SERVO 保持当前 EE，切换后重新观测再恢复。接触段绝不切换。

### 3.4 VIEW-MEM：stance 变了，目标记忆不能丢

- **记忆单元**：`M = {(p_i, σ_i, view_i, t_i)}`，`p_i` 是目标点在 base 系的 3D 位置，`σ_i` 是置信度，`view_i` 是当时可见性，`t_i` 是时间戳。
- **更新**：头双目可见时，用双目三角化 + 2D 分割更新 `p_i`；腕部可见时，用腕部 2D 中心 + 头双目深度/已知 EE 位姿做近距更新；透明/遮挡时降低 `σ_i`，不直接删。
- **stance 改变后**：用新头相机位姿重投影 `M`；如果目标回到视野，更新；如果仍不可见，触发一次小范围搜索（左/右/前倾）；如果 `σ_i` 太低，交给 VLA 重规划/语言重试。
- **腕部-头部交接**：头双目负责全局米制定位，腕部负责最后 3 cm 的 2D 对齐；腕部无内参时不做绝对米制，只做相对像素误差，避免引入标定误差。

### 3.5 平衡/接触：用演示安全集做「证书」，不自己做全身 RL

- **硬约束**：`s ∈ S_task`；`vx=vy=vw=0`；height 只在 `height_prior ± 0.02 m` 内；waist yaw/pitch 只在 `±0.08 rad` 内。这个范围远小于 min/max 尾部，接近演示的 q01–q99/工程余量。
- **速率限制**：height ≤0.02 m/s、waist ≤0.3 rad/s；一次切换 0.5–1.0 s，避免 WBC 跟踪不上。
- **接触冻结**：`phase ∈ {align, contact, release}` 时 stance 不变；如果必须调整，先退回 approach，再调整，再重新对准。
- **fallback**：候选评估失败/超时 → 保持 `s_prior`；检测到摔倒/大角度倾斜 → 停止手臂动作，回 `s_prior`，等待 reset；不尝试「用手撑地」这类未验证动作（BRACE 只作为探索项）。
- **底层平衡**：交给官方 WBC；SVS 只输出 pivot 目标，不直接控制腿。这样不违反单模型规则，也不承担全身 RL 的风险。

### 3.6 四个 G0 free wins：先修接口，再谈创新

这三个不需要训练，几小时就能验证，但可能是榜单上最便宜的涨分点：

1. **pivot 顺序**：`yaw=waist[0]`、`pitch=waist[2]`、`roll=waist[1]`。在单任务通道分别发 `+0.1 rad pitch` 和 `+0.1 rad roll`，看头相机是「低头/抬头」还是「左右侧倾」。如果方向不对，先修映射。
2. **零 pivot 不是中性**：用任务均值 `[0,0,0, yaw_mean, pitch_mean, roll_mean, height_mean]` 作为 baseline，和全零对比。重点看机器人是否一上来就蹲下/被限幅、头相机高度是否明显低于演示。
3. **任务级 stance lookup**：用语言指令查 `s_prior`；匹配失败用全局 `[0, 0.172, 0, 0.737]`。这不是「第二个模型」，是一张 32 行的配置表；先验证它是否比常数 stance 更稳。
4. **HF `action.pivot` 陷阱**：不要用 HF 的 `action.pivot[3:6]` 当 waist 标签；用 `action.waist_action_joint` / `lower_body[-3:]` + `action.base_command` 重建。先做一个小脚本，对比重建的 pivot 和 WLA server 的定义。

如果这四个 free wins 就能带来可测提升，说明「身体接口」确实被低估；如果它们没有提升，SVS 的搜索收益也要打折，应该优先把工程投到 CHUNK-SERVO。这是本轮最重要的「止损门」。

### 3.7 单模型合规：一个 VLA + 一个确定性搜索器 + 一张配置表

- **在线学习模型**：只有官方 WLA/VLA 一个。SVS 的 stance 搜索是确定性枚举 + 解析效用，没有学习权重；BODY-LABEL 是离线标注；lookup table 是配置。
- **辅助头**：如果训练 phase/visibility 预测头，优先作为训练期辅助任务，或并入同一个 VLA checkpoint；不单独部署第二个策略网络。
- **最宽解释**：如果组委会把「任何产生动作的模块」都算模型，SVS 走 C2（确定性控制器，不算模型）并提交说明；BODY-LABEL 走 C1（仅训练期）；不部署 C3 的第二个学习策略。
- **文档**：在提交说明里写清楚「一个 VLA + 一个基于规则的 stance 选择器 + 一张 32 行先验表」，避免被误判为多模型。

## 4. 创新点清单

### 4.1 SVS：任务级 stance 先验 + 事件触发的安全集搜索（主押注）

- **动机**：33k 演示显示 height 在任务内几乎恒定、waist pitch 只有小幅调整；泛化把目标挪走后，固定的任务级 stance 可能让目标出视野/超可达域。需要的不是连续全身策略，而是「换一个安全 stance」的离散选择。
- **与现有方案的差异**：不是 whole-body VLA/RL，不学连续 stance；不是固定三脚架；不是「更大模型」。它把 pivot 当成慢速视角/可达域控制器，用演示分布做安全证书，只在触发时搜索。
- **技术可行性**：pivot 语义已由官方代码确认；stance 先验可由 32 个 stats.json 直接算；候选集只有 27 个；可见性/可达性可用头双目 + URDF 解析计算；切换由 WBC 执行。无需新数据、无需训练大模型。
- **所需资源**：1 张 24GB GPU（复用 WLA 推理/微调）；1–2 周工程（标注脚本 + planner + 单任务验证）；1 台 G1 单任务通道；不需要大规模仿真集群。
- **落地步骤**：G0 接口验证（pivot 顺序/零值/lookup/HF pivot）→ G1 离线标签 → G2 仿真候选评估/切换稳定性 → G3 单任务 A/B（5 个 stance-heavy + 2 个 stance-light）→ G4 泛化扰动 → G6 全量 dry run。
- **风险**：pivot 执行限幅/跟踪未知；stance 切换可能让 WBC 抖动；可见性估计在透明物体上不准；单任务与全量评测的分布不同。缓解：G0 先验证；只在非接触段切换；±0.02 m/±0.08 rad 小步；失败回 `s_prior`；不移动 base。

### 4.2 BODY-LABEL：把「线上拿不到的特权信号」蒸馏成 stance/view/reach/phase 标签（使能项）

- **动机**：演示里有 `state_d435`、`state_torso`、`ee_pose_gripper_torso`、`gripper_controls`、`recomputed_ee_valid`，线上 API 没有；但这些信号正好能标出「当时身体在哪、相机看哪、目标可不可达、处于什么阶段」。不利用就是浪费 33k 成功演示。
- **与现有方案的差异**：现有自动标注多关注物体/接触/affordance；BODY-LABEL 关注 **任务级 stance 先验 + 安全集 + 视角质量 + 可达裕度 + 阶段**，并且明确处理「离线特权 → 线上可观测」的映射。
- **技术可行性**：stats.json 已给出全部通道的 min/max/mean/std/分位数；头相机外参可由 waist 刚体映射恢复；phase 可用夹爪/EE 速度/距离阈值自动切；reach 可用 URDF 正运动学。全离线，CPU 可跑。
- **所需资源**：1 名标注/感知工程 1–2 周；无需人工逐帧标；存储 10–50 GB（关键帧 + 标签）。
- **落地步骤**：先做 32 任务 stance 统计表 → 再做 5 任务 phase/visibility 抽查 → 再做头相机外参拟合 → 最后把标签接到 SVS/CHUNK-SERVO。
- **风险**：任务级统计不能代表帧级行为；phase 阈值在变形物体/透明物体上不稳；头相机外参拟合受安装误差影响。缓解：用 q01–q99 而非 min/max；phase 只做粗分（接触/非接触）；外参用多任务联合拟合 + 单任务验证。

### 4.3 VIEW-MEM：stance 改变后的 3D 目标记忆与重定位（感知项）

- **动机**：stance 一变，头相机视角就变；如果目标记忆还是旧视角的 2D 框，CHUNK-SERVO 会把「旧画面」当「新画面」。透明/遮挡/人为干扰下，单帧检测不可靠，需要跨视角记忆。
- **与现有方案的差异**：不是纯 6D 位姿跟踪；用头双目米制 + base 系点记忆 + 腕部近距更新；显式处理「stance 改变导致的重投影」；不依赖 depth/force。
- **技术可行性**：头双目已校正，可直接三角化；目标分割可用 Grounded SAM 2/颜色/尺寸先验；base 系点记忆只需 3D 点 + 置信度；重投影是解析计算。
- **所需资源**：1 张 GPU 做分割/深度（可与 WLA 共用）；1 周工程；无需训练。
- **落地步骤**：先做单任务「目标静止、机器人腰动」的重投影误差 → 再做「目标被移动」的记忆更新 → 再做「遮挡/透明」的置信度衰减 → 最后接 CHUNK-SERVO。
- **风险**：透明物体深度空洞；腕部无内参导致近距米制漂移；目标被完全遮挡时记忆过期。缓解：置信度衰减 + 触发重看；腕部只做 2D；过期就重规划。

### 4.4 BRACE：双臂支撑/反平衡的角色标注（探索项，不进主路径）

- **动机**：G1 短臂 + 高重心；某些低处/远处目标可以靠「非主导臂轻撑桌面/抓握容器」分担反作用力，或把非主导臂当配重。33k 演示里有双臂协同，但没有显式的「支撑/配重」标签。
- **与现有方案的差异**：现有双臂 VLA 多把两臂当两个操作手；BRACE 显式标注「主导手/支撑手/配重手」，并把支撑接触作为 stance 安全集的一部分。
- **技术可行性**：可从 EE 位姿/接触/力（离线无 force，只能用几何接近）自动标注候选；仿真可验证支撑是否减少滑动；真机需要柔顺控制/力限，风险高。
- **所需资源**：2–3 周；仿真 + 单任务；需要额外安全评审。
- **落地步骤**：只做离线标签 + 仿真可行性 → 如果支撑接触能稳定降低滑动，再考虑单任务真机；否则剪枝。
- **风险**：单模型合规（支撑策略不能是第二个模型）；支撑接触可能让 WBC 误判；桌面/物体承重未知；失败可能把物体压坏。**默认不进入比赛主路径。**

- **保留**：CHUNK-SERVO 的 30 步规划 + 5 步视觉伺服 + 演示检索相对目标 + 轻量数字孪生标定；DG-KEYFRAME；GEO-RESIDUAL；FACT-VLA；单任务通道 A/B；单模型合规。

- **剪枝**：
  - 不做连续全身 stance 伺服（演示数据不支持）。
  - 不做全身 RL / sim-to-real 策略训练（风险/资源不匹配）。
  - 不移动 base（`vx=vy=vw=0`）；pivot 只动 waist + height。
  - 不在接触段变 stance。
  - 不用 min/max 当安全区；不用零 pivot 当 baseline。
  - 不做 32 个任务各一个策略；lookup table 是配置，不是模型。
  - 不把榜单任务排名当难度表；用单任务通道测。

## 6. 实验门与竞赛策略（摘要）

| 门 | 问题 | 通过标准 | 失败则 |
|---|---|---|---|
| G0 | pivot 顺序/零值/lookup/HF pivot 是否正确 | +pitch 让头低/抬，+roll 让头侧倾；零 pivot 明显低于 demo；lookup 不崩 | 先修接口，暂停 SVS |
| G1 | stance 先验/安全集/phase 标签是否可信 | 5 任务抽查 phase F1 ≥0.75；先验与 demo 均值误差 <0.01 m/0.02 rad | 退回任务级统计，不做帧级 |
| G2 | 候选评估/切换是否稳 | 仿真无摔倒；切换后可见性/可达性提升；p99 planner ≤50 ms | 缩小候选集/只做 lookup |
| G3 | 单任务 A/B 是否涨点 | 5 个 stance-heavy 中 ≥3 个方向为正；扩样后聚合 +10pp；2 个 stance-light 不回归 | 只保留 lookup，剪掉 search |
| G4 | 泛化扰动是否恢复 | 目标挪远/遮挡/人为移动后，重看恢复 ≥70%，≤300 ms | 加 VIEW-MEM，减少 search |
| G5 | 延迟是否可接受 | planner p99 ≤50 ms；端到端 p99 ≤150 ms | 降候选数/异步 |
| G6 | 全量 dry run 是否安全 | 32×10 无摔倒；pivot 在安全框；内存/端口稳定 | 回滚到 CHUNK-SERVO baseline |
| G7 | 消融是否支持主张 | lookup/search/visibility/balance/freeze 各自有贡献 | 剪掉无贡献项 |
| G8 | 统计是否显著 | 配对 A/B + bootstrap 95% CI；320 trials SE≈2.6pp | 不宣称小差异 |

**任务组合**（先验，不是榜单排名）：

- **S 档（stance 先验差异大/接触多）**：OrganizeTools（pitch 均值最高 0.239、任务内有 8.3° 调整）、PickOutBatteries（height 最低 0.7295、接触）、PaperCupStacking（height 最低 0.7273、堆叠）、StorePaddle（pitch/yaw）、FoldTowel（变形物）、Unlock（低 height + 接触）、ArrangeTestTubes（插入）、PackPhone（插入）、ZipUp（拉链）、HangCup（悬挂）。
- **对照档（stance 轻）**：PlugCharger（height 0.740、pitch 0.164）、StoreCups、StoreEarphones、PourOutMedicine（height 变化≈0、pitch 0.183）、RemovePinnedNote。用来检查「不回归」。
- **优先级**：`priority_t = (q_t × Δ_stance_t + q'_t × Δ_servo_t) / cost_t`；`q_t` 是「失败发生在够不到/看不到」的比例，`q'_t` 是「失败发生在最后 3 cm」的比例。用单任务通道估，不用榜单。

## 7. 风险与止损

- **pivot 执行语义不确定**：官方 WLA 代码是 A，但挑战赛评测端是否同样执行未验证。G0 先用小幅指令；不对就退回 CHUNK-SERVO。
- **WBC 跟踪/限幅**：height/waist 目标可能被限幅或滤波；切换太快会抖。用小步 + 速率限制 + 单任务验证。
- **视角变化破坏伺服**：stance 一变，CHUNK-SERVO 的图像目标会漂。切换期间冻结手臂，切换后重投影；VIEW-MEM 必须有。
- **透明/遮挡目标**：双目深度空洞，可见性估计不可靠。降低权重，优先腕部 2D，必要时重规划。
- **标注噪声**：任务级统计可信，帧级 phase 不可全信。phase 只做粗分；G1 抽查。
- **单模型合规**：lookup/planner 是确定性控制器；如果官方最宽解释，走 C1/C2 并文档化；不部署第二个学习策略。
- **评测噪声**：320 trials、每任务 10 次；单任务 A/B 用配对/多次；不要把 1–2pp 当结论。
- **时间**：先做 G0 free wins 和 lookup（1 周），再做 search（1–2 周）；如果 G3 不涨，立即剪掉 search，保留 CHUNK-SERVO。

## 8. 一句话押注

**演示告诉我们 G1 的 stance 是「任务级静态先验」而不是连续全身策略；真正的泛化缺口是目标被挪走后先验失效。SVS 用 33k 演示自动标注安全 stance 集和 view/reach/phase，在非接触段事件触发地在安全集内重选一个「看得见、够得着、不破坏平衡」的 stance，再交给 CHUNK-SERVO 做最后 3 厘米——这是在不违反单模型规则、不重训全身 VLA 的前提下，最可能把 30% 往上推的结构性缺口。**

# 第 13 轮产物 · STANCE-VIEW SEARCH (SVS) 技术报告

> 检索/复核日期：**2026-10-29（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「STANCE-VIEW SEARCH」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是给它们补一个慢速身体环。

## 0. 结论与边界

### 0.1 一句话结论

33k 演示显示 G1 的 stance 是**任务级静态先验**（height 任务内 q10–q90 ≤0.0001 m，waist pitch ≤0.145 rad），不是连续全身策略；因此 SVS 不做连续 stance 伺服，而是用离线 BODY-LABEL 生成任务级 stance 先验/安全集，在泛化导致目标出视野/超可达域且非接触时，事件触发地在安全集内搜索一个新 stance，慢速切换后交给 CHUNK-SERVO。三个接口问题（pivot 顺序、零 pivot、HF `action.pivot` 陷阱）必须先当 G0 修掉；否则后面的创新会被一个低级映射错误抵消。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、WLA 源码、数据集 stats、排行榜页面直接核实 | 规则、API、pivot 映射、33,276 eps、32 任务统计、榜单 29.7% |
| B | 我们在公开数据/网页上做的分析，可复现 | q01/q99 修正、任务级 stance 表、头相机 pitch 相关、运行页非 10% 整数倍 |
| C | 设计假设，需 G0–G8 验证 | stance 搜索 +Xpp、可见性阈值、切换 0.5–1.0 s、WBC 跟踪稳定 |

### 0.3 本轮不做什么

- 不从零训 VLA/World Model；官方 WLA 已开源 6B 基座。
- 不做连续全身 stance 控制/全身 RL/sim-to-real 策略训练；演示数据不支持，风险也不匹配。
- 不做第二个在线学习模型；SVS 搜索是确定性枚举，BODY-LABEL 是离线标注，lookup table 是配置表。
- 不移动 base：`vx=vy=vw=0`；pivot 只动 waist + height。
- 不在接触段变 stance；不在 align/contact/release 段切换。
- 不做 6D 物体位姿网络；用头双目米制点 + 2D 分割 + 3D 记忆。
- 不做 30Hz 广域网伺服；执行层继续用 CHUNK-SERVO 的 5 步块。
- 不把预览榜单的任务排名当难度表；任务优先级用单任务不计分通道测。
- 不把 HF 的 `action.pivot[3:6]` 当 waist 标签；按 WLA server 的映射重建。

### 0.4 关键修正：min/max 会骗人，必须看分位数

本轮最初用 min/max 看 stance，得到「腰 yaw 最大 0.876 rad、height 最大变化 0.132 m」，很容易得出「演示大量使用 stance，应该做连续全身控制器」。但把 32 个任务的 q01/q99 和 q10/q90 拉出来后，结论相反：

| 统计口径 | waist yaw 最大 | waist pitch 最大 | height 最大 |
|---|---:|---:|---:|
| min–max（全部帧） | 0.876 rad (50.2°) | 0.506 rad (29.0°) | 0.132 m (13.2 cm) |
| q01–q99（98% 帧） | 0.132 rad (7.6°) | 0.246 rad (14.1°) | 0.0001 m |
| q10–q90（80% 帧） | 0.087 rad (5.0°) | 0.145 rad (8.3°) | 0.0001 m |

结论：**min/max 的大值集中在 1–2% 尾部，可能是 reset/首尾过渡/少数动态帧；不能当作持续行为。** 演示是「任务级静态 stance + 小幅腰 pitch 调整」。这不削弱 SVS，反而把方案从「学连续全身策略」（数据不够）改成「用安全先验 + 事件触发重选」（数据刚好够）。

## 1. 事实核对

### 1.1 比赛规则（A）

官方参赛手册（中文/英文两版，2026-10-29 通过 `r.jina.ai` 复核）核实：

| 项 | 规则 |
|---|---|
| 模型 | 所有任务须基于**同一模型**完成，不得混合多个模型一起测试；模型类型不限 |
| 任务 | 32 项桌面任务 |
| 次数 | 每任务 10 次独立运行 |
| 泛化 | 5 类各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰 |
| 时限 | 单次真机执行上限 **180 s** |
| 排名 | 先比 32 任务总平均成功率；相同看总平均步骤分；再相同看更早提交 |
| 部署 | 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态必须隔离 |
| 测试通道 | 另有**不计分的单任务测试通道**，可用于单任务成功率/步骤分验证 |

**对方案的约束**：SVS 必须每端口独立、CPU 轻量、不抢 GPU；不能是第二个策略模型；单任务通道是唯一敢做 A/B 的地方。

### 1.2 提交 API（A）

提交模板 README（2026-10-29 复核）给出：

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640** |
| 本体 | 双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str` |
| 动作空间 | `control_space` 仅 `"joint"` 或 `"ee"`，二者互斥 |
| 共享动作 | `action.left_gripper [1]`、`action.right_gripper [1]`、`action.pivot [7]` |
| EE 动作 | `action.left_ee_pose_gripper_base [6]`、`action.right_ee_pose_gripper_base [6]`（绝对目标位姿，xyz+rpy，base 系） |
| chunk | `action_chunk_size` ≥1，固定；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action` |
| token | `metadata.token` 握手校验一次；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile** |
| 监控 | 评测端逐调用记录延迟、波动、动作统计规律，作为结果可信度的一部分 |

**关键推论**：`action_chunk_size=30`、控制频率 30Hz 时，一次 `get_action` 之后有 **1 秒开环执行**；chunk 内没有新观测，也没有打断机制。视觉伺服要生效，必须把 chunk 降到 3–8 步，或把 VLA 规划与伺服执行拆成双频。控制频率未在 README 中写死；本报告默认 30Hz，必须在单任务通道实测。

### 1.3 pivot 的真实语义（A）

官方 `unifolm-wla` 的 `action_server_wbc_msgpack_unitree.py`（2026-10-29 复核）在文件头写明：

```text
action.pivot (1, T, 7)  vx, vy, vw, yaw, pitch, roll, height
    vx/vy/vw/height are the same 4 values as base_command; yaw/pitch/roll
    come from the waist (lower_body last 3, ordered yaw,roll,pitch) remapped
    into pivot's yaw,pitch,roll order.
```

构造代码：

```python
# pivot = [vx, vy, vw, yaw, pitch, roll, height]. The waist (lower_body
# last 3) is ordered [yaw, roll, pitch], so remap: yaw=waist[0],
# pitch=waist[2], roll=waist[1].
waist = unnorm[:, SLICES["waist_joint"]]    # (T,3) = [yaw, roll, pitch]
pivot = np.concatenate([
    vx_vy, vw,
    waist[:, 0:1],   # yaw
    waist[:, 2:3],   # pitch
    waist[:, 1:2],   # roll
    height,
], axis=1).astype(np.float32)               # (T,7)
```

映射表：

| pivot 索引 | 含义 | 来源 |
|---:|---|---|
| 0 | vx | `base_command[0]` |
| 1 | vy | `base_command[1]` |
| 2 | vw | `base_command[2]` |
| 3 | yaw | `lower_body[-3]` / `waist[0]` |
| 4 | pitch | `lower_body[-1]` / `waist[2]` |
| 5 | roll | `lower_body[-2]` / `waist[1]` |
| 6 | height | `base_command[3]` |

**四个陷阱：**

1. **pitch/roll 顺序。** 数据集 waist 是 `[yaw, roll, pitch]`，pivot 是 `[yaw, pitch, roll]`。把 `lower_body[-3:]` 原样塞进 `pivot[3:6]` 会交换 pitch/roll；机器人可能「想前倾却侧倾」，头相机视角也跟着错。这个 bug 在日志里很难看出来，必须在 G0 用 +0.1 rad pitch / +0.1 rad roll 分别验证。
2. **height=0 不是中性值。** 演示的 height 均值约 0.737 m（跨任务 0.7273–0.7400 m），零动作的 height=0 远低于此。官方 example policy 返回零动作只是 stub；如果直接拿零 pivot 当 baseline，可能一上来就蹲下/被限幅，成功率和安全性都不可信。
3. **HF 数据集的 `action.pivot` 不是 challenge pivot。** HangCup 的 HF `action.pivot` 是 `[0,0,0,0,0.15,0,0.74]`，而同一帧的 waist 是 `[-0.01,-0.0037,0.1806]`；OrganizeTools 的 `action.pivot[3]/[4]` 的 std 是 0.147/0.118，而 waist yaw/pitch 的 std 是 0.075/0.093。**不要用 HF 的 `action.pivot[3:6]` 当 waist 标签**；用 `action.waist_action_joint` / `lower_body[-3:]` + `action.base_command` 按 WLA server 的映射重建。
4. **pivot 是「目标」不是「状态」。** 评测端/WBC 可能限幅、滤波、按跟踪误差执行；`action.pivot` 不等于机器人下一帧的真实姿态。G0 必须记录 `pivot_cmd` 与 `lower_body`/`state_d435` 的跟踪误差，不能假设命令即到位。

### 1.5 头相机/身体-视角耦合（A/B）

- 头双目：基线 **58.2526 mm**，HangCup 的 `camera_matrix_left` 近似 `fx=282.3693, cx=311.5250, fy=282.7521, cy=256.6277`；`rectified: true`。腕部 `camera_params` 只有 `color/ir1/ir2`，**没有内参矩阵**。

- `action.pivot.height` 与膝角/相机高度的相关性随任务变化：HangCup 0.84、OrganizeTools −0.29、StorePaddle −0.74、PickOutBatteries −0.53、FoldTowel 0.37。**不能用统一的「height=膝角」线性模型**；height 是 WBC 命令，映射依赖任务/腿型/接触。安全做法是用演示分布做安全集，而不是用膝角反推。
- 结论：**stance 是视角的慢速控制器，但不是连续云台。** 一个 5–8° 的腰 pitch 变化足以把低处/远处目标从画面边缘拉回中心；一个 5° 的 yaw 变化足以绕过轻度遮挡。对桌面任务，这比让手臂去「够到画面外」更安全。

### 1.6 G1 形态与操作约束（A）

- G1 高约 1.32 m、重约 35 kg；官方参数页给的手臂工作半径约 0.45 m、腿长约 0.6 m。桌面任务的目标常在身前 0.4–0.8 m、高度 0.7–1.1 m；短臂 + 固定头意味着 **身体位置直接决定「能不能够到」和「能不能看到」**。
- 35 kg 的高重心 + 演示尾部最大 29° 腰 pitch 意味着前倾会移动 CoM；虽然演示证明 WBC 能处理，但 SVS 不应该把 min/max 当安全区，也不应该在接触段动身体。
- API 没有深度/力/触觉；头双目是唯一米制深度来源；腕部只能做 2D 对齐或一次性标定后的近距更新。

- **VLA-Δ**（arXiv 2610.21306，2026-10-15）用动作变化检测做关键片段标注。

**手眼标定（腕部无内参不是绝路）**

- **CalibAll**（arXiv 2511.17001，2025-11）在未知相机位姿下做联合标定。

**平衡/接触（CoM/支撑多边形可做代理，但不必自己训 RL）**

- **DreamControl**（2026）用 CoM-aware 世界模型做人形平衡；**ULC**（arXiv 2507.06905，2025-07）用对抗运动先验做通用人形控制；**BAT**（arXiv 2604.01064，2026-04）做平衡感知的全身跟踪；**PILOT**（arXiv 2601.17440，2026-01）做触觉/平衡容错。

这些是动态全身控制；SVS 只用它们的 **CoM/支撑多边形指标** 做候选排序，底层平衡仍交给官方 WBC。

**空白**：没有工作把「任务级静态 stance 先验（来自 33k 成功演示）+ 事件触发的安全集 stance 搜索 + 头双目视角评估 + CHUNK-SERVO」组合到 UniBot 挑战赛。这个空白不是「再训一个更大的 VLA」，而是「把已有的身体接口用对」。

## 2. 问题形式化

### 2.1 时间模型

```text
慢环  stance search     事件触发；候选评估 20–50 ms；切换 0.5–1.0 s
中环  VLA plan          ~1 Hz；30 步 chunk；每步 1/30 s
快环  CHUNK-SERVO       6.7 Hz；5 步块；每块 5/30 ≈ 167 ms
```

设 VLA 在第 `k` 次调用返回 `T_p=30` 步动作；CHUNK-SERVO 把它切成 `B=6` 个 5 步块。stance 只在块边界、且 phase 不在 contact/align/release 时改变；改变后丢弃/重取当前 VLA chunk，避免「旧 chunk 按旧身体执行」。

### 2.2 状态/动作

- stance 状态：`s = [yaw, pitch, roll, height]`（对应 pivot 的 3–6 维）。
- pivot 动作：`a_pivot = [0, 0, 0, yaw, pitch, roll, height]`；`vx=vy=vw=0`。
- 手臂动作：`a_ee = [left_ee_6, right_ee_6]`（base 系绝对位姿）或 `a_joint`；本方案用 `ee`，与 CHUNK-SERVO 的相对目标兼容。
- 夹爪：`g = [left, right]`。
- 观测：`o = (I_head_left, I_head_right, I_wrist_left, I_wrist_right, q_arm, p_ee, g, l)`；其中 `l` 是语言。
- 隐藏变量：`x = (p_target, phase, contact, visibility, reach)`；离线可由特权字段近似，线上由 BODY-LABEL/VIEW-MEM 估计。

### 2.3 头相机位姿模型

头相机固定在躯干上；忽略腰平移的柔性，假设刚体：

```text
T_base_d435(s) = T_base_torso(q_waist) * T_torso_d435
q_waist = [yaw, roll, pitch]  # 数据集顺序
```

- `T_base_torso(q_waist)` 由 URDF 正运动学给出；`T_torso_d435` 是固定安装变换。
- 离线用 `state_d435` 和 `waist_state_joint` 拟合 `T_torso_d435`（6-DoF 刚体，robust least squares）；线上用 `lower_body[-3:]` 重建。
- 由于 `pitch_d435 ≈ pitch_waist + const`（抽样相关 1.000），旋转部分很稳；平移部分用多任务联合拟合，再用单任务验证。
- 像素投影：

```text
p_cam = R_base_d435^T (p_base - t_base_d435)
u = fx * p_cam.x / p_cam.z + cx
v = fy * p_cam.y / p_cam.z + cy
```

### 2.4 可见性

给定目标点云 `P_t = {p_i}`（base 系）和候选 stance `s`：

```text
V(s) = (1/|P_t|) Σ_i  visible_i(s) * center_i(s) * depth_i(s)
```

- `visible_i(s)`：投影落在图像内、`z` 在 `[z_min, z_max]`、未被机器人连杆/场景遮挡。
- `center_i(s) = exp(-((u_i-u0)^2 + (v_i-v0)^2) / (2σ^2))`，`u0,v0` 是图像中心；越靠中心越好。
- `depth_i(s)`：头双目深度有效（视差/置信度）则为 1，否则 0.5/0；透明物体可降权。
- 遮挡：离线用点云 z-buffer；线上用头双目深度 + 机器人连杆投影近似。不要训练新网络。

### 2.5 可达性

```text
p_shoulder(s) = FK_torso(s) * p_shoulder_torso
R(s) = clip(1 - ||p_target - p_shoulder(s)|| / L_arm, 0, 1)
```

- `L_arm` 用 URDF 的实际臂长/工作空间，不用「臂展 0.45 m」的粗略值。
- `R=0` 表示目标在臂展边缘或外；`R≥0.15` 表示有 15% 余量；`R` 只用于候选排序，不单独硬拒（因为末端姿态/夹爪方向也影响可达）。
- 若所有候选 `R<0`，保持 `s_prior`，让 VLA 尝试伸展/换手；不要为了 `R` 冒进到安全集外。

### 2.6 平衡/安全集

**硬安全集**（来自演示 q01–q99）：

```text
S_task = {s : yaw ∈ [yaw_q01, yaw_q99],
              pitch ∈ [pitch_q01, pitch_q99],
              roll ∈ [roll_q01, roll_q99],
              height ∈ [height_q01, height_q99]}
```

**工程安全框**（更保守，默认用这个）：

```text
S_task^+ = {s : |yaw - yaw_prior| ≤ 0.08,
                |pitch - pitch_prior| ≤ 0.08,
                |roll - roll_prior| ≤ 0.05,
                |height - height_prior| ≤ 0.02}
            ∩ S_task
```

- 为什么不用 min/max：尾部是 reset/过渡/异常帧，不是持续安全区。
- **平衡代理** `B(s)`：
  - 首选：`B(s) = ||(s - s_prior) / σ||_2`（标准化距离）；离先验越远，越可能超出演示平衡域。
  - 若仿真/URDF 可算：`p_com = Σ m_i p_i(q)/Σ m_i`，支撑多边形取双脚接触点凸包，`B(s) = max(0, d_min - d(p_com, edge))`；但候选的腿关节未知，只能用当前腿姿/最近 demo 帧近似，所以 CoM 只做二次排序，不做硬拒。
- 硬约束：`s ∈ S_task^+`、速率限制、phase gate、`vx=vy=vw=0`。

### 2.7 效用/约束

```text
U(s) = w_v V(s) + w_r R(s) - w_b B(s) - w_d D(s) - w_p ||s - s_prior||²
s.t.  s ∈ S_task^+,
      |Δheight|/Δt ≤ 0.02 m/s,
      |Δwaist|/Δt ≤ 0.3 rad/s,
      phase ∉ {align, contact, release},
      vx = vy = vw = 0
```

默认权重：`w_v=1.0, w_r=1.0, w_b=0.5, w_d=0.3, w_p=0.2`。这些是工程初值，G2/G3 网格搜索；不学习。

- 切换阈值：`max_s U(s) - U(s_current) > 0.05` 才切换；否则保持，避免抖动。
- 迟滞：连续 3 帧触发才动作；一次 episode 最多 2–3 次 stance 改变；冷却 1 s。
- 切换：`s(t) = s_cur + (s_new - s_cur) * smoothstep(t/T)`，`T=0.8 s`；期间冻结手臂目标，切换后重新观测。

### 2.8 事件触发/阶段门

**触发条件**（满足任一，且 `phase ∈ {approach, transport, recover}`）：

```text
V(s_current) < 0.60
R(s_current) < 0.15
target_reprojection_error > 15 px for 3 frames
target_3d_jump > 0.03 m (human disturbance / object moved)
VLA confidence < threshold (if available)
```

**阶段定义**（粗分，BODY-LABEL 自动标）：

| phase | 判据（示例） | 允许 stance 改变 |
|---|---|---|
| approach | 夹爪开、EE 向目标移动、距离 > 5 cm | 是 |
| align | 夹爪开、EE 距离 ≤5 cm、速度低 | 否 |
| contact | 夹爪闭合/接触信号、EE 速度低 | 否 |
| transport | 夹爪闭合、EE 向目标容器移动 | 是（小步） |
| release | 夹爪打开、目标距离近 | 否 |
| recover | 任务完成后/失败重试/无接触 | 是 |

阶段判据用夹爪开度、EE 速度、目标距离、`gripper_controls`（离线）组合；不训练新模型。阈值在 G1 抽查。

### 2.9 目标记忆

```text
M = {(p_i, σ_i, view_i, t_i)}
```

- `p_i`：base 系 3D 点；`σ_i`：置信度；`view_i`：上次可见性；`t_i`：时间戳。
- 可见时：头双目三角化 + 2D 分割更新 `p_i`，`σ_i ↑`；腕部可见时：用腕部 2D 中心 + 头双目深度/EE 位姿做近距更新。
- 不可见时：`σ_i` 按时间衰减；stance 改变后用新 `T_base_d435` 重投影；若仍不可见，触发小范围搜索；若 `σ_i < 0.3`，让 VLA 重规划/语言重试；若 `σ_i < 0.1`，丢弃。
- 腕部-头部交接：头双目负责全局米制；腕部只做 2D 像素误差/近距相对更新，不做绝对米制（无内参）。

### 3.3 stance planner 伪代码

```python
def stance_step(obs, mem, phase, s_prior, safe_set):
    s_cur = obs.pivot[3:7]  # [yaw, pitch, roll, height]
    if phase in ("align", "contact", "release"):
        return s_cur, "frozen"
    if not trigger(obs, mem, phase):
        return s_cur, "no_trigger"

    P = mem.target_points()
    best_s, best_u = s_cur, utility(s_cur, P, s_prior, s_cur)
    for s in candidates(s_prior, safe_set):
        if not in_safe_set(s, safe_set):
            continue
        u = utility(s, P, s_prior, s_cur)
        if u > best_u + 0.05:
            best_s, best_u = s, u
    if best_s == s_cur:
        return s_cur, "keep"
    return smooth_transition(s_cur, best_s, duration=0.8), "switch"

def utility(s, P, s_prior, s_cur):
    V = visibility(s, P)        # 0..1
    R = reach_margin(s, P)      # 0..1
    B = balance_proxy(s, s_prior)
    D = norm(s - s_cur)         # 切换代价
    Pn = norm((s - s_prior) / sigma)
    return 1.0*V + 1.0*R - 0.5*B - 0.3*D - 0.2*Pn

def candidates(s_prior, safe_set):
    for dy in (-0.08, 0, 0.08):       # rad
        for dp in (-0.08, 0, 0.08):
            for dh in (-0.02, 0, 0.02):
                s = s_prior + [dy, dp, 0, dh]
                if in_safe_set(s, safe_set):
                    yield s
```

**执行约定**：`pivot = [0, 0, 0, yaw, pitch, roll, height]`；切换期间保持 EE 目标，切换完成后丢弃当前 VLA chunk 并重新取一帧观测/新 chunk；不要用旧 chunk 配新身体。

### 3.4 VIEW-MEM 伪代码

```python
def update_memory(mem, obs, T_base_d435, phase):
    if target_visible(obs.head_left, obs.head_right):
        p = triangulate(obs.head_left, obs.head_right, target_mask)
        mem.add(p, sigma=0.9, view=1.0, t=now)
    elif target_visible(obs.wrist_left) or target_visible(obs.wrist_right):
        p = wrist_to_base_2d(obs, mem, T_base_d435)
        mem.update(p, sigma=0.6, view=0.5, t=now)
    else:
        mem.decay(sigma=0.95, t=now)

def reproject(mem, T_base_d435):
    for m in mem:
        uv = project(T_base_d435, m.p)
        m.visible = in_image(uv) and depth_valid(uv)
    return mem

def needs_relook(mem):
    return max(m.sigma for m in mem) < 0.3 or mean(m.visible) < 0.6
```

### 3.5 与 CHUNK-SERVO 的集成

- VLA 仍输出 30 步；CHUNK-SERVO 切成 6 个 5 步块，每块内做视觉修正。
- stance 改变只允许在块边界；改变后 **丢弃当前 30 步 chunk**，重新调用 VLA；不要在旧 chunk 上继续执行。
- 切换期间：冻结 EE 目标（保持当前 base 系位姿），让 WBC 完成 stance；切换后 VIEW-MEM 重投影，CHUNK-SERVO 重新锁定目标。
- 延迟预算：stance 搜索 20–50 ms + 切换 800 ms；只在非接触段发生；对 180 s 任务可接受。
- 如果 VLA 延迟高（RTT 大），stance 搜索用当前帧异步计算，但只在块边界应用；不要让 stance 搜索阻塞 `get_action`。

## 4. 关键推导

### 4.1 头相机位姿与投影

由 URDF：

```text
T_base_torso(q) = T_base_waist * T_waist_torso(q_yaw, q_roll, q_pitch)
T_base_d435(q)  = T_base_torso(q) * T_torso_d435
```

- 旋转：`R_base_d435 = R_base_torso * R_torso_d435`；`p_cam = R_base_d435^T (p_base - t_base_d435)`。
- 投影：`u = fx * p_cam.x / p_cam.z + cx`，`v = fy * p_cam.y / p_cam.z + cy`。
- 由于 `pitch_d435 ≈ pitch_waist + const`，旋转拟合的残差应很小；如果残差大，先查 pivot 顺序/URDF 关节顺序。
- 平移 `t_torso_d435` 用多任务 `state_d435` 拟合；如果只能拿到 `state_d435` 的部分任务，用 URDF 先验 + 少量任务校准。

### 4.2 可见性推导

- 目标点云 `P_t` 的每个点投影后，落在图像内且深度有效的比例，衡量「目标有多少在视野里」。
- 居中权重让目标靠近光心，减少镜头畸变/视差误差；对腕部 2D 对齐也更友好。
- 遮挡用 z-buffer：离线把场景点云/机器人连杆投影到同一图像，比较深度；线上用头双目深度 + 连杆投影。透明物体深度缺失时，`depth_i=0.5`，并降低 `V` 的权重。
- 该指标不需要训练，可在 G1 用人工抽查的 100 帧验证排序。

### 4.3 可达裕度推导

- `p_shoulder(s)` 由躯干位姿 + 肩部固定偏移得到；`L_arm` 是 URDF 的肩到夹爪最大伸展。
- `R = 1 - d/L_arm`；`R<0` 表示目标超出最大伸展；`R∈[0,0.15]` 表示边缘；`R>0.15` 表示舒适。
- 该指标只考虑位置，不考虑末端姿态；所以它是排序项，不是硬约束。真正的可达性还要看夹爪朝向、碰撞、腕部限位。

### 4.4 平衡代理推导

- 简化 CoM：`p_com = Σ m_i p_i(q) / Σ m_i`；支撑多边形取双脚接触点凸包；`d_min = min_edge signed_distance(p_com_xy)`。
- 候选 stance 的腿关节未知，`p_com` 只能用当前腿姿/最近 demo 帧近似；所以 `B(s)` 只做二次排序。
- 硬安全来自 `S_task^+`：演示成功帧的 q01–q99 + 小工程余量。这个「数据证书」比未标定的 CoM 模型更可靠。
- 如果仿真能给出候选 stance 的腿关节（例如 WBC 逆解），再用真正的 CoM 裕度；否则不要用 CoM 硬拒。

### 4.5 速率限制与切换稳定性

- `s(t) = s_cur + (s_new - s_cur) * (3τ² - 2τ³)`，`τ=t/T`，`T=0.8 s`。
- 最大 height 变化 0.02 m → 速度 ≤0.025 m/s；最大 waist 变化 0.08 rad → 速度 ≤0.1 rad/s；都低于 WBC 的典型跟踪能力。
- 切换期间冻结手臂，避免「身体动 + 手臂动」耦合导致末端大偏差；切换后重新观测/重取 chunk。
- 迟滞 + 冷却 + 每 episode 次数上限，防止在阈值附近抖动。

### 4.6 为什么事件触发优于连续 stance 伺服

1. **数据**：演示 height 任务内几乎恒定，waist pitch 只有 <8.3° 的 q10–q90 调整；连续伺服是外推，没有监督。
2. **安全**：接触段动身体会破坏接触；事件触发把动作限制在 approach/transport/recover。
3. **延迟**：搜索 20–50 ms，切换 0.8 s；只发生少数次，不拖慢 180 s 任务。
4. **可解释**：每次切换都有 `V/R/B` 分数和候选，可在日志里复盘；连续策略难定位。
5. **合规**：确定性枚举 + 规则，不是第二个学习模型。

```text
G6 fail? -> 回滚到 CHUNK-SERVO baseline
G7/G8 fail? -> 不宣称收益；保留阴性结果
```

### 6.6 预期结果（C，不是承诺）

- G0 的接口修复可能带来「无训练」的稳定性提升；这是最便宜、最该先做的。
- 任务级 lookup 可能在 stance-heavy 任务上带来小幅提升；如果连 lookup 都没效果，search 的收益大概率也不显著。
- search 的收益主要应出现在「目标被挪远/挪低/遮挡」的泛化 trial，而不是 demo 分布内的 trial；评估时要看分层结果。
- 如果 search 在 demo 分布内也大幅涨点，要怀疑评测/实现有问题，而不是庆祝。

## 7. 竞赛策略

### 7.1 320 trials 当投资组合

- 32 任务 ×10 次 = 320 trials；总体成功率 SE ≈ `sqrt(p(1-p)/320)`；`p=0.3` 时约 2.6pp（本报告按 p=0.3 取 2.6pp）。
- 单任务 10 次，SE ≈15pp；不要用单任务 1–2 次差异做决策。
- 先交安全 baseline 锁 tie-break；再交 SVS 改进；保留回滚。
- 单任务通道用于 A/B；全量提交用于最终排名。

### 7.2 节奏

| 周 | 工作 | 门 |
|---|---|---|
| W0 | API adapter；G0 pivot 顺序/零值/HF pivot；baseline 单任务 | G0 |
| W1 | BODY-LABEL 32 任务表；头相机外参；lookup baseline | G1 |
| W2 | stance search + 仿真；切换稳定性 | G2 |
| W3 | 单任务 A/B（5+2 任务） | G3/G5 |
| W4 | 泛化扰动（位置/遮挡/人为移动） | G4 |
| W5 | 全量 dry run；端口/内存/延迟 | G6 |
| W6 | 消融/统计；最终提交/回滚 | G7/G8 |

### 7.3 止损

- G0 不过：不做 SVS；先修接口。
- G3 不过：只保留 lookup；剪掉 search。
- G6 不安全：回滚 CHUNK-SERVO；不拿摔倒换涨点。
- 任何「+Xpp」没有配对 A/B/CI：不写进结论。
