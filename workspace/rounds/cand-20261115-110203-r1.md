# 第 5 轮（灵感循环第 5 轮；本轮灵感：「用户需求分析」×「视觉编码器」）

> **基线**：第 4 轮 InstructGauge-WR（IP-328–333；定义 448–467；引理 59–62；实验 E457–E472）。第 3 轮 InstructGauge 五不变式、CVC 闭环与严格退化链继续继承不变。
> 本轮纪律：**需求只收缩验收口径、不扩张能力；编码器只提供召回证据、不单独裁决验收**。两个新灵感各沿一条轴升级 WR v4，且任一环节不可用都必须能逐级退回 WR v4 → InstructGauge v3 → ToolGauge。

## 0. 直觉与动机

**灵感 1（用户需求分析 → 从「一句指令」到「可验收的需求树」）**
直觉：工程师说「帮我把这个盲区看清楚」，这不是一条动作，而是一份**需求**——它有目标（看清）、约束（不碰工件、不超时、不越位）、偏好（先便宜后精细）和**验收准则**（缺陷可见、复检通过）。软件需求工程几十年的教训是：需求必须先被分解、消歧、排优先级，并绑定可执行的验收测试，否则「实现正确」与「需求正确」会悄悄脱钩。所以正确的接口不是 `NL→ι`，而是 `NL→需求树 R`，再由 `R` 编译出（可能多条）指令规格 `ι`；每条 `ι` 必须能追溯回某个需求叶子，每个叶子都必须携带一个**能返回 fail 的谓词**。这一步把「语义已经正确」的错觉，转成「验收未通过」的可检测事实。

**灵感 2（视觉编码器 → 把验收准则落到可测视觉证据，但要防分布外自信）**
直觉：验收「看清了」最终要靠图像。手工特征（边缘、反光、深度）可解释但覆盖面窄；现代视觉编码器（DINOv2 / CLIP / SigLIP）语义覆盖广，却高维不可分解。二者不是替代关系，而是**证据源分层**：编码器负责「这与需求描述的概念是否同类」的召回，几何/深度/多视图负责「尺寸、位姿、遮挡、计数是否精确满足」的核验。编码器真正的危险不是不准，而是**在分布外仍然自信**——所以余弦相似度绝不能当概率用，必须把 OOD 分数、SE(3) 等变性误差与共形 p 值一起打包成证书。

**灵感 3（两者耦合 → 需求—证据可追溯，专门防「验收幻觉」）**
直觉：需求分析定义「要证明什么」，视觉编码器定义「拿什么证明」。最危险的耦合是：一条含糊需求被编码器的高相似度「证明」为满足，于是**假阳性验收**沿着一条看起来完整、可审计的追溯链一路绿灯。解法不是禁用任一组件，而是三根结构支柱：**需求可证伪**（每个验收叶子都必须是能失败的谓词）、**证据分层**（编码器只给召回与软证据，硬验收由几何/深度/多视图回执独立裁决，冲突时以硬证据为准）、**追溯完整性**（禁止孤儿动作与孤儿需求，未验证必须显式标记为 `UNVERIFIED`）。再叠加**需求冲突的字典序消解**，让安全约束始终支配。

## 1. 研究问题（本轮要回答什么）

- **Q1（需求可验收性）**：自然语言需求能否被编译成「可失败、可追溯、不扩权」的验收准则树，而不是新的模糊性来源？
- **Q2（视觉证据可信性）**：视觉编码器作为验收证据源，需要哪些不变量（等变性）、不确定度（OOD / 共形）与冗余条件，才能让「相似即满足」不成立？
- **Q3（耦合的可审计性）**：需求与证据之间的正反馈（假阳性验收）能否被双证书与追溯完整性压回「可检测、可界」？

## 2. 三条设计原则（雏形，正式化见产物区定义 468–487）

**P1 需求可证伪（Falsifiable Requirement）**
每个需求叶子必须编译成能返回 `pass/fail/unknown` 的谓词 `a(x)`，且存在非空反例集使其返回 `fail`；禁止「看起来不错」这类不可证伪准则。无法编译的叶子一律标记 `NEEDS_CLARIFICATION`，整体退回默认需求 `r₀`（等价于 WR v4 目标）。

**P2 证据分层（Evidence Stratification）**
视觉编码器只产生候选与软证据（召回、排序、冲突提示），**不得单独判 pass**；硬验收（几何、位姿、遮挡、计数、力/温度回执）必须由 v4 的深度/多视图/回执独立裁决。软硬证据冲突时以硬证据为准，记录 `conflict` 并要求复核。

**P3 追溯完整性（Traceability Completeness）**
任何被执行的动作必须沿 `need → requirement → ι → action → receipt` 链可追溯到某个需求叶子或显式默认；任何需求叶子必须有至少一条证据路径，或显式状态 `UNVERIFIED`。禁止孤儿动作、禁止孤儿需求。

## 3. 与基线的接口（如何退化）

- 需求不可分解 / 不可证伪 / 冲突不可解 ⇒ 使用默认需求 `r₀`，等价于 WR v4 目标；
- 视觉编码器 OOD / 等变性误差超界 / 分层共形失效 ⇒ 关闭编码器召回，仅用 v4 几何-视觉证据；
- 追溯链断裂 ⇒ 拒绝提交该动作，等价于 WR v4 的 CVC 拒绝；
- 冲突涉及安全约束且不可同时满足 ⇒ 拒绝并请求澄清，绝不降级安全；
- 所有增强失效 ⇒ InstructGauge-WR v4；v4 失效 ⇒ InstructGauge v3 ⇒ ToolGauge。

## 4. 预期贡献

1. 一个「需求树 → 可验收谓词 → 指令规格」的编译口径，把需求模糊性隔离在编译期而不是执行期；
2. 一个「编码器召回 + 几何硬验收」的证据分层，明确编码器不得单独裁决验收；
3. 一个带 OOD / 等变性 / 分层共形三重证书的视觉证据可信度框架；
4. 一条完整可证伪路径：E473–E488 覆盖需求编译、追溯完整性、编码器可信度、假阳性验收、冲突安全、对抗注入与退化等价。

## 5. 本轮最大风险

**一句话**：需求可证伪化会把「含糊但其实正确」的意图误判为 `NEEDS_CLARIFICATION`，而视觉编码器的分布外自信又可能让假阳性验收伪装成「已追溯、已校准」的绿灯，二者叠加的真实残余风险是**审计通过但物理未满足**。

## 2. 形式化定义（核心 468–477；478–487 为派生记法，见符号表）

**定义 468（需求树 NeedTree）**
需求树 `R = (N, E, r₀)`，节点 `n = (type, text, prio, ac)`，其中 `type ∈ {GOAL, CONSTRAINT, PREFERENCE, ACCEPTANCE}`，`ac` 为验收谓词（仅 ACCEPTANCE 叶子必填）。约束节点进入硬约束集 `C_hard`；偏好节点只影响排序，不进入可行域。

**定义 469（可证伪验收谓词）**
谓词 `a: X → {pass, fail, unknown}` 可证伪，当且仅当存在非空反例集 `X_fail ⊆ X` 使 `∃x ∈ X_fail: a(x) = fail`。若 `a` 恒真、或不可在有限预算内测量，则编译失败并标记 `NEEDS_CLARIFICATION`。

**定义 470（需求→指令编译）**
`compile: R → 2^Ι ∪ {⊥}` 满足：
1. 每条 `ι` 的目标来自某个 `GOAL` 叶子；
2. `tools(ι) ⊆ T₀`（继承第 3 轮能力闭包）；
3. 每条 `ι` 携带验收映射 `A_ι: L(R) → {a_ℓ}`；
4. 若某硬约束不可满足，或某叶子需要 `T₀` 之外的工具，则 `compile(R) = ⊥`。
因此需求编译**只收缩、不扩张**可执行能力。

**定义 471（需求-概念绑定）**
对每个验收叶子 `ℓ`，绑定 `Γ_req(ℓ) = (p_ℓ, φ, τ_ℓ)`：`p_ℓ` 是概念原型嵌入，`φ` 是视觉编码器，`τ_ℓ` 是该叶子的判据阈值或共形分位。绑定必须登记来源（人工标注 / 演示 / 合成），未登记来源的绑定进入冷启动保守模式。

**定义 472（视觉证据与共形 p 值）**
编码器证据 `e_ℓ(x) = cos(φ(x), p_ℓ)`。在分层标定集 `D_s` 上定义非一致性分数 `s_i = 1 − e_ℓ(x_i)`，共形 p 值
`p_ℓ(x) = (1 + #{i ∈ D_s : s_i ≥ s(x)}) / (|D_s| + 1)`。
仅当 `p_ℓ(x) ≥ α` 时 `x` 进入**召回候选**；p 值不得单独解释为「验收通过」。

**定义 473（编码器可信证书 EncoderCert）**
`EncoderCert(x, ℓ) = (ood_score, equiv_err, p_value, agree, coverage_ok)`，其中
`ood_score` 为特征空间 Mahalanobis 距离或 energy 分数；
`equiv_err = E_{g∈SE(3)} ‖φ(g·x) − ρ(g)·φ(x)‖ / ‖φ(x)‖`（编码器宣称等变时）或跨视角一致性误差；
`agree` 为多编码器相似度的标准差；
`coverage_ok` 为分层共形覆盖检验结果。
证书有效当且仅当 `ood_score ≤ δ ∧ equiv_err ≤ ε_eq ∧ p_value ≥ α ∧ agree ≤ a_max ∧ coverage_ok`。

**定义 474（分层验收）**
`hard(ℓ, x)` 由几何/深度/位姿/遮挡/计数/力温回执等硬谓词裁决，值域 `{PASS, FAIL, UNKNOWN}`；`soft(ℓ, x) = 1[EncoderCert valid ∧ p_ℓ(x) ≥ α]`。
`accept(ℓ, x)` 规则：
- `hard = FAIL` ⇒ `FAIL`（无论 soft 如何）；
- `hard = PASS` ⇒ `PASS`，若 `soft = 0` 同时记 `conflict`；
- `hard = UNKNOWN` 且 `soft = 1` ⇒ `UNVERIFIED` + 需复核（**编码器不得单独放行**）；
- 其余 ⇒ `UNVERIFIED`。

**定义 475（需求追溯矩阵 Trace）**
`Trace = {(ℓ, ι, a, ev, r)}`，`ℓ ∈ L(R)`、`ι ∈ compile(R)`、`a` 为动作、`ev` 为证据（含 EncoderCert 与硬验收结果）、`r` 为回执。完整性约束：
1. `∀a` 被执行，`∃(ℓ, ι, a, ·, ·) ∈ Trace`，否则为**孤儿动作**，提交被拒绝；
2. `∀ℓ ∈ L(R)`，`status(ℓ) ∈ {PASS, FAIL, UNVERIFIED}`，且 `UNVERIFIED` 必须在提交报告中显式出现，禁止静默省略。

**定义 476（需求冲突消解）**
需求间采用字典序 `≻_req`：`SAFETY > HARD > GOAL > PREFERENCE`，同层按预注册 `prio` 降序。若两条 `SAFETY` 需求冲突且不可同时满足，`resolve` 返回 `⊥` 并请求澄清；任何情况下不得为满足低层需求而违反高层约束。

**定义 477（需求满足度与分层覆盖）**
`SAT(R, x) = (1/|L(R)|) Σ_{ℓ∈L(R)} 1[accept(ℓ, x) = PASS]`。
在预注册显著性 `α` 下，要求对每个需求类型层 `s`：
`P(SAT_s ≥ 1 − ε) ≥ 1 − α`。
若某层样本不足或覆盖检验失败，该层标记 `UNVERIFIED`，并回退到父层/全局阈值，而不是假装覆盖成立。

```python
# IP-334 NeedTree-Compiler
class NeedTreeCompiler:
    def __init__(self, ontology, tool_closure):
        self.ontology = ontology
        self.T0 = tool_closure              # 继承 v3 能力闭包

    def parse(self, text):
        """NL -> 类型化需求树；失败返回 None"""
        try:
            return self._parse_typed(text, self.ontology)
        except GroundingError:
            return None

    def is_falsifiable(self, leaf):
        """必须能构造反例；恒真/不可测一律不可证伪"""
        return leaf.predicate is not None and leaf.predicate.has_counterexample

    def compile(self, text):
        R = self.parse(text)
        if R is None:
            return None, "NEEDS_CLARIFICATION"
        for leaf in R.acceptance_leaves():
            if not self.is_falsifiable(leaf):
                return None, "NEEDS_CLARIFICATION"
            if not subset(tools_of(leaf), self.T0):
                return None, "CAPABILITY_VIOLATION"
        return R, "OK"

    def to_iota(self, R):
        specs = []
        for g in R.goal_leaves():
            iota = make_iota(g, R.hard_constraints(), R.preferences())
            iota.acceptance = {l: l.predicate for l in R.acceptance_leaves()}
            iota.source_leaves = R.leaves_under(g)
            specs.append(iota)
        return specs

# IP-335 ReqTrace-Matrix
class ReqTrace:
    def __init__(self):
        self.rows = []                      # append-only
        self.status = {}                    # leaf -> UNVERIFIED/PASS/FAIL

    def register(self, leaf, iota, action, evidence, receipt):
        self.rows.append((leaf, iota, action, evidence, receipt))
        if leaf not in self.status:
            self.status[leaf] = "UNVERIFIED"

    def mark(self, leaf, verdict):
        self.status[leaf] = verdict

    def complete(self, executed, R):
        traced = {a for (_, _, a, _, _) in self.rows}
        orphans = [a for a in executed if a not in traced]
        missing = [l for l in R.acceptance_leaves() if l not in self.status]
        return (not orphans and not missing), orphans, missing

# IP-336 Vision-Encoder-Bank
class VisionEncoderBank:
    def __init__(self, encoders, prototypes, ood_stats):
        self.encoders = encoders            # DINOv2 / CLIP / SigLIP
        self.prototypes = prototypes        # leaf -> {encoder: prototype}
        self.ood_stats = ood_stats          # 每层均值/协方差

    def embed(self, img):
        return {name: enc.encode(img) for name, enc in self.encoders.items()}

    def recall(self, leaf, img):
        z = self.embed(img)
        sims = [cosine(z[n], self.prototypes[leaf][n]) for n in self.encoders]
        return float(np.mean(sims)), float(np.std(sims))

    def ood_score(self, img, stratum):
        z = np.concatenate([v.ravel() for v in self.embed(img).values()])
        mu, cov = self.ood_stats[stratum]
        return float(mahalanobis(z, mu, cov))

    def equivariance_error(self, img, leaf):
        # 对采样变换 g 检验 phi(g x) 与 rho(g) phi(x) 的相对误差
        errs = []
        for g in sample_se3(self.n_transforms):
            errs.append(rel_err(self.embed(g.apply(img)),
                                g.act(self.embed(img))))
        return float(np.mean(errs))

# IP-337 EncoderCert
class EncoderCertifer:
    def __init__(self, delta_ood, eps_eq, alpha, agree_max):
        self.delta_ood, self.eps_eq = delta_ood, eps_eq
        self.alpha, self.agree_max = alpha, agree_max

    def certify(self, leaf, img, bank, calibration, stratum):
        sim, agree = bank.recall(leaf, img)
        ood = bank.ood_score(img, stratum)
        eq = bank.equivariance_error(img, leaf)
        p = calibration.conformal_p(stratum, 1.0 - sim)
        cov = calibration.coverage_ok(stratum)
        valid = (ood <= self.delta_ood and eq <= self.eps_eq
                 and p >= self.alpha and agree <= self.agree_max and cov)
        return EncoderCert(ood, eq, p, agree, cov, valid)

# IP-338 Layered-Acceptance
def layered_accept(leaf, x, cert, hard_suite):
    h = hard_suite.evaluate(leaf, x)        # PASS / FAIL / UNKNOWN
    soft = cert.valid and cert.p >= cert.alpha
    if h == "FAIL":
        return "FAIL", ("soft_conflict" if soft else "hard")
    if h == "PASS":
        return "PASS", ("conflict" if not soft else "agree")
    if soft:
        return "UNVERIFIED", "soft_only_needs_review"
    return "UNVERIFIED", "no_evidence"

# IP-339 Req-Conflict-Resolver
RANK = {"SAFETY": 0, "HARD": 1, "GOAL": 2, "PREFERENCE": 3}
def resolve(reqs):
    ordered = sorted(reqs, key=lambda r: (RANK[r.kind], -r.prio))
    chosen = []
    for r in ordered:
        if any(conflicts(r, c) for c in chosen):
            if r.kind == "SAFETY":
                return None, "SAFETY_CONFLICT_REQUEST_CLARIFICATION"
            continue
        chosen.append(r)
    return chosen, "OK"

# IP-340 主闭环（50Hz 主路径不变，重活异步）
def needgauge_ve(M, blind_spot, ell=None):
    # 1. 需求编译（失败即退化 v4）
    R, status = M.needc.compile(ell) if ell else (M.default_need, "DEFAULT")
    if R is None:
        return instructgauge_wr(M, blind_spot, None)

    # 2. 冲突消解
    specs, status = M.resolver.resolve(M.needc.to_iota(R))
    if specs is None:
        return None, "NEEDS_CLARIFICATION"

    # 3. 受 WR v4 约束的分块规划
    iota = specs[0]
    C = M.iac.plan_chunk(iota, M.lbox.hypothesize(blind_spot, iota),
                         M.tools, M.budget_left(blind_spot), M.drift_bound(blind_spot))
    if not M.kloop.verify_prefix_closed(C)[0]:
        C = M.iac.plan_chunk(iota, M.lbox.hypothesize(blind_spot, iota),
                             M.tools, 1, M.drift_bound(blind_spot))

    # 4. 逐动作：软召回 + 硬验收 + 先登记后执行
    for a in C.actions:
        leaf = iota.leaf_for(a)
        cert = M.encert.certify(leaf, M.wristcam.latest_frame(), M.bank,
                                M.calib, str(leaf.stratum))
        verdict, src = layered_accept(leaf, M.env.observe(), cert, M.hard)
        M.trace.register(leaf, iota, a, (cert, verdict, src), M.tcv.latest())
        if verdict == "FAIL":
            C = C.truncate_before(a)
            M.trace.mark(leaf, "FAIL")
            break
        if verdict == "UNVERIFIED":
            M.trace.mark(leaf, "UNVERIFIED")
            continue                        # 记录在案，提交时需复核
        M.trace.mark(leaf, "PASS")
        M.env.apply(a)

    # 5. 追溯完整性检查（孤儿动作/孤儿需求一律拒绝提交）
    ok, orphans, missing = M.trace.complete(M.env.executed(), R)
    if not ok:
        return None, ("TRACE_INCOMPLETE", orphans, missing)

    # 6. 复用 WR v4 的 CVC / SpatialCert / ROS 发布
    return M.wr.commit(C, iota, M.trace)
```

## 4. 推导

**引理 63（需求不扩权）**
对任意可编译的需求树 `R`，`compile(R)` 中每条指令满足 `tools(ι) ⊆ T₀`，且拒绝任何需要 `T₀` 之外工具的叶子。故需求层是基座能力集的**过滤器**，不是新的能力来源。
证明：由定义 470 条件 2 与 `compile` 的 `CAPABILITY_VIOLATION` 分支直接得到；`T₀` 与第 3 轮能力闭包相同，故对 WR v4 也是子集关系。∎

**引理 64（追溯完整性的归纳保持）**
若每个动作在 `env.apply` 之前先 `trace.register`，且提交前调用 `trace.complete`，则任何一次提交通过时，所有已执行动作都存在 `need→req→ι→action→receipt` 链，且所有验收叶子状态均非静默缺失。
证明：对执行步数归纳。初始空轨迹满足；第 `k` 步先登记再执行，登记行携带叶子与指令，故新动作非孤儿；提交检查要求 `orphans = ∅ ∧ missing = ∅`。∎

**引理 65（编码器证据有界）**
在分层内可交换且标定有效的条件下，对同分布样本 `p_ℓ(x)` 满足 `P(p_ℓ(x) ≥ α) ≥ 1 − α`；若 `ood_score > δ` 或 `equiv_err > ε_eq` 或 `agree > a_max`，则证书无效，`soft = false`。因此**单靠编码器不可能产生 PASS**，假阳性验收必须由硬验收套件出错导致。
证明：共形 p 值的有效性给出第一句；证书有效性的合取条件给出第二句；再由定义 474，`accept = PASS` 当且仅当 `hard = PASS`。∎

**引理 66（安全支配）**
`resolve` 采用字典序 `SAFETY > HARD > GOAL > PREFERENCE`，且安全冲突返回 `⊥`。故任何被 `resolve` 接受的指令集都不会违反高层硬约束；不存在「为满足目标而降级安全」的执行路径。
证明：对排序后的贪心逐项做情形分析；安全项冲突直接返回，非安全项冲突只是被跳过。∎

**引理 67（退化等价）**
编码器不可用或证书全部无效时，`soft = false`，`layered_accept` 退化为硬验收（`PASS/FAIL/UNKNOWN`），与 WR v4 的几何-视觉证据路径一致；需求树不可用时使用 `r₀`，其目标等价于 WR v4 默认目标；追溯层在 `ι = ι₀` 时只是恒等登记。故完整退化链在行为上等价于 WR v4。
证明：逐分支比较定义 474 与第 4 轮 CVC 判定；`r₀` 与 v4 默认目标相同；追溯登记不改变动作序列。∎

## 8. 本轮最大风险

**一句话**：视觉编码器的高维语义空间并不天然可分解为「需求叶子」，一旦原型绑定与分布外检测同时失效，系统会产出**链条完整、证书齐全、但物理验收为假**的审计结果，而且「可追溯」本身会让复核者更倾向于信任它——真正需要防守的是**审计幻觉**，不是单个模块的精度。
