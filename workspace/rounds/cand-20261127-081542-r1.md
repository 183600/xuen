## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（多任务学习 → 32 个任务其实是一张 32×5 的任务×泛化轴网格，排行榜按宏平均计分）**
直觉：官方只设通才赛道（F20），排名是 32 任务的**宏平均**成功率，而不是样本加权平均。于是两个反直觉推论：(a) 训练按样本数混采（F25）与计分目标并不对齐——谁的任务样本多/谁的正则强，谁就暗中获得更大权重；正确做法是**任务均衡采样 + 最弱任务正则**，因为把最弱任务拉高 1% 对宏平均的贡献，可能大于把最强任务拉高 5%。(b) 5 条泛化轴横切所有任务，每任务每轴各 2 次（F20），真正的评测单元不是 32 个任务，而是 32×5=160 个「任务×轴」格；轴级能力（抗背景、抗干扰、未见物体、位置变化、抗人扰）是**跨任务共享**的，应该用共享的轴适配器学，而不是在每个任务里各学一遍。核心反直觉点：**多任务学习的第一问题不是「怎么共享」，而是「共享什么、隔离什么」——共享轴能力与技能先验，隔离会互相拉扯的任务动力学。**

**灵感 2（多机协同 → N 台机器人不是 N 份模型，而是同一个模型上的 N 条异构 episode 流）**
直觉：规则明令单模型、禁止按任务混用多模型（F21），所以「多机协同」在赛道上不能是「多个 checkpoint 投票」。它只能是三件事：(a) **一个共享后端**承载 N 个端口（F22），靠跨端口动态微批分摊 6B 冻结 VLM 的前向成本；(b) **reset 期 episode 签名路由**——用首帧+语言判断当前任务族与泛化轴，激活对应的轻量专家/adapter，episode 全程复用，避免每步切换；(c) **延迟公平**——不能让一个长任务或一个大 batch 把别的端口拖过截止期。核心反直觉点：**多机协同真正的敌人不是算力，而是跨端口状态污染与队头阻塞；协同的收益来自「共享计算、隔离状态」，而不是「共享状态」。**

**灵感 3（多机协同 × 多任务学习 → 双臂是「机内双机协同」，双手协作是隐藏的分数洼地）**
直觉：手册把「双手协调」列为三大能力之一（F21），每个数据集/动作都含双臂与 lower_body（F27），但多数队伍会只学主动臂、放任闲置臂漂移。两条低成本高收益的措施：(a) **闲置臂锁定**——用语言+首帧预测哪些臂参与任务，未参与臂输出保持当前位姿，避免无谓抖动触发失败判定；(b) **双臂共享潜变量 + 相对位姿一致性**——双手任务不是两个单臂策略拼接，而是共享一个 latent 再分头解码，并用相对位姿/同步约束把两手绑在一起。核心反直觉点：**双臂协同的关键不在「多一个头」，而在「少一份自由度」——用一致性约束消掉两手互相打架的自由度。**

**三者统一**：多任务学习回答「一个模型如何容纳 32×5 个能力单元」（宏平均对齐 + 技能/轴因子化专家），多机协同回答「一个模型如何同时服务 N 条异构流」（共享后端 + 端口隔离 + 专家缓存 + 公平调度），双臂协同回答「机内两个执行器如何作为一个整体控制」（共享 latent + 一致性 + 闲置臂锁定）。三者把第 2 轮的 I2/I6/I9 从「数据/单端口」推进到「训练—服务一体化的单模型多任务系统」。

## 0. 计分对齐与核心形式化（本轮新增）

### 0.1 排行榜目标与采样错位

设任务集 $T$（$|T|=32$），任务 $t$ 的 10 次试验成功率为 $S_t=\frac{1}{10}\sum_{i=1}^{10}s_{t,i}$，步骤分为 $P_t$。排行榜主指标与并列裁决为：

$$
J=\frac{1}{32}\sum_{t\in T}S_t,\qquad J_p=\frac{1}{32}\sum_{t\in T}P_t .
$$

官方 loader 在 `multi_task: true` 时按样本数比例从各任务子集采样（F25），其期望梯度最小化的是 $\sum_t n_t R_t$（$n_t$ 为任务样本数），一般不等价于最小化宏平均 $J$。**结论：必须把采样从「样本比例」改成「任务均衡/分层比例」（PR6），否则 110 语料会淹没 32 考题，且易任务会支配训练信号。**

### 0.2 负迁移与迁移矩阵

对任务 $t$，定义加入来源任务 $s$ 的数据后的迁移增益：

$$
T_{s\to t}=R_t(\theta_{C\cup\{s\}})-R_t(\theta_C),
$$

其中 $C$ 为 32 考题集合，$R_t$ 用 L0 代理（动作似然/进度头/关键点跟踪）估计，家族级再用 L2 真机确认。若 $T_{s\to t}<0$ 且 $|T_{s\to t}|$ 超过阈值，则裁掉该孪生对。宏观负迁移用 $\mathrm{NT}=\sum_t\min(0,\max_s T_{s\to t})$ 监控。

### 0.3 因子化条件专家（I10 的形式）

把策略参数写成「共享 + 技能残差 + 轴残差」：

$$
\theta=\theta_{\text{shared}}+\sum_{k=1}^{K_s}\alpha_k A_k+\sum_{a=1}^{5}\beta_a B_a ,
$$

其中 $A_k,B_a$ 为低秩 LoRA（F26 支持 action head LoRA），门控 $(\alpha,\beta)=g_\phi(o_0,l)$ 只依赖 reset 首帧 $o_0$ 与语言 $l$。**零初始化** $\alpha=\beta=0$ 使初始模型严格等于基座，天然满足「标称不掉点」与「可回退」。episode 内门控固定，可预合并为每端口的等效 adapter，per-step 不增加路由开销。

### 0.4 多机服务目标

N 个端口各自有 episode 状态 $h_p$、可变 chunk 长度 $T_a^{(p)}$、调用截止期。共享后端计算 $f_\theta(o,e_p)$，其中 $e_p$ 是 reset 期选定的专家组合。要求：

$$
\forall p\ne q:\ h_p\cap h_q=\varnothing,\qquad \mathrm{p99}(\text{latency})<\eta\cdot\text{budget}(p),
$$

且端口间无 BatchNorm/运行统计/KV 缓存共享。$f_\theta$ 共享参数与只读权重，$h_p$ 独占。

## 1. 创新点清单（每点：动机 / 与现有差异 / 可行性 / 资源 / 落地步骤 / 风险）

### I1 v3 考纲校准五轴增广引擎 ★★★★★
- **本轮增量**：I1 的增广管线天然产生「图像 ← 施加了哪条轴/多大剂量」的标签，**免费**成为 I10 轴路由器的监督信号；增广采样从「按任务」升级为「按任务×轴均衡」，避免某一轴被过采样。
- 其余（考纲卡、剂量-响应、位置重拼接的物理可行性判据）同 v1.1。风险：轴标签只在合成数据上可靠，真实评测轴分布仍有偏差；用 L0 轴分类混淆矩阵 + 真机抽测校准。

### I2 v3 宏平均对齐数据引擎 ★★★★★
- **动机**：官方按样本数混采（F25）与宏平均计分错位；110 语料体量会淹没 32 考题；孪生迁移可能负迁移。
- **本轮增量**：
  1. **分层任务均衡采样**：先按组采样（challenge / twin / far 固定比例），组内任务等概率，再按质量分采 episode。取代样本数比例。
  2. **梯度冲突处理**：共享主干上用 PCGrad/梯度手术；结构性上用 I10 的技能/轴专家隔离冲突。二者叠加。
  3. **负迁移门禁**：用 §0.2 的迁移矩阵，孪生对先过 L0 再放量；远任务无正迁移则归零。
  4. 保留 v1.1 的孪生表与示教质量加权（作为任务内的 episode 权重）。
- **可行性**：高。采样器是纯数据工程；联合训练可用 1×24GB frozen-VLM 起步，全参 action expert 4–8 卡。
- **落地步骤**：①实现分层采样器并做分布单测（统计 batch 内任务频率=1/32）；②接入质量权重；③在留出集上算迁移矩阵；④首轮共训；⑤L0 家族消融后再放孪生量。
- **风险**：任务均衡会相对削弱易任务，可能损失少量宏平均；用 worst-k 与宏平均双指标监控，必要时对已达标任务退火权重。负迁移仍是最大数据风险。

### I3 接触任务族关键点视觉伺服回退 ★★★★（维持）
- 六要素同 v1.1：通用 chunk 负责接近段、几何伺服负责接触段，同一 PolicyService 内混合推理（PR2/PR7 边界待书面确认）；`ee` 控制空间 + per-step 调用天然支持；开放词汇关键点零训练起步；触发滞回 + 低置信回退；I3' 降级预案（训练时辅助监督）保留。
- 本轮补：双手接触任务（如插拔、整理）需与 I12 的角色/一致性约束联用；先由 I12 的手臂审计确定范围。

### I4 人手干预感知门控 + 自适应 chunk ★★★★（维持）
- 六要素同 v1.1：手部检测 + `obs_delta_indices` 历史栈判别干预（<50ms）；状态机 INTERFACED→停持→重估→续做；干预态短 chunk / 稳定态长 chunk。
- 本轮补：**chunk 长度与 I11 调度联合标定**。大 chunk 降低调用频率、增大单次计算预算，但也降低对人扰的反应速度；用 `budget = control_period × T_a − margin` 把 chunk 选择纳入服务预算。双臂场景需检测「只碰一只手」的干预。

### I5 非标称示教合成 + 得分点对齐恢复 ★★★★（维持/微调）

- 本轮增量：扰动幅度按 I1 的轴分布采样；合成数据入训时同样走 I2 v3 的「任务×轴均衡」采样，避免恢复类样本淹没法线样本。
- 风险同 v1.1：合成分布与真实偏离失配；里程碑检测器误差。用置信门控 + 5% 人工抽检。

### I6 v3 确定性低延迟服务基座 ★★★（降）

- **本轮修正/否决**：①「N 份独立进程、每端口各加载一份 6B」正式否决（12.46GB × N 不经济，F26）；②p99 目标不再拍脑袋 40ms，改为按 `control_period × T_a` 推预算并报告分布；③官方 model_server 是 WBC/msgpack 形态，需改造成提交模板的 PolicyService（F23），不要直接复用协议。
- 风险：接口映射（相机名、lower_body→pivot）未核对前，延迟再好也无意义；列为 P0 工程项。

### I8 v3 评测运营闭环 + 分级消融注册表 ★★★★

- **落地步骤**：①指标实现；②矩阵报表；③首个真实用例 = I2 v3 采样器 vs 官方比例采样的 L0 对比；④I10 路由 vs 无路由；⑤每月复盘相关性。
- 风险：离线代理与真机相关性建立慢；先用历史真机结果回填对齐点。

### I9 reset 期检索类比迁移 ★★★★（维持/接线）
- 同 v1.1：`reset()` 每 episode 一次（F18），物体嵌入→物体-技能库检索→动作先验软注入；距离阈值门控，超阈退回无先验。
- **本轮增量**：检索特征（物体嵌入距离、最近邻技能分布）直接作为 I10 路由器的输入特征之一；检索到的技能类别可作为技能专家的先验偏置。二者共用一次 reset 计算，不重复开销。
- 风险同 v1.1：误检索伤标称任务；VLM 嵌入对同类不同外观不敏感。合规需书面确认。

### I10 单模型技能×轴因子化专家路由（新） ★★★★★

- **动机**：32×5 网格中任务动力学与泛化轴相互纠缠；单套 LoRA 容量有限，简单全参共训又易负迁移。排行榜宏平均意味着「补最弱格」最值钱，而不同格需要不同能力。目标是**一个 checkpoint 内**显式分离「共享技能」与「轴鲁棒性」。
- **与现有方案差异**：①直接 SFT/单 LoRA：所有任务抢同一容量；②按任务训 32 个模型：违反单模型规则（F21）；③仅 prompt 条件化：无参数隔离，弱任务仍被淹没。本点用**低秩加性专家 + 零初始化软路由**，在单模型内获得「按需隔离」。
- **技术可行性**：中-高。官方支持 action head / VLM 的 LoRA（F26），6B 基座单卡 24GB 可微调；路由器是轻量 MLP/注意力池化，训练成本低；轴标签由 I1 免费产生。
- **所需资源**：1×24GB 起步（LoRA + 路由头）；若训练全量多专家，2–4×A100；路由器训练约 1 GPU 日；无需新数据下载（复用 I1 合成 + 32 任务 + 110 语料）。
- **落地步骤**：
  1. 由 I1 生成带轴标签的增广集；由语言/任务名生成技能族标签（LLM 初筛 + 人工校对）。
  2. 训练路由器（首帧 4 相机池化 + 语言嵌入 + I9 检索特征 → 技能分布 + 轴分布），用标签监督 + 熵/负载均衡正则。
  3. 在 action head 注入技能 LoRA 与轴 LoRA，门控零初始化；先冻结路由器训练专家，再联合微调。
  4. **L0 消融五种**：无路由（单 LoRA）/仅技能/仅轴/技能+轴/技能+轴+硬路由；指标 = 标称宏平均不掉点 + worst-k 提升 + 轴分类混淆。
  5. 通过后 L2 top-2 真机确认（≥2 任务 × 2 次）。
- **风险**：①轴路由在真实首帧上不可靠 → 误路由伤标称；缓解：零初始化残差 + 软路由 + 置信阈值 + 超阈退化为基座，L0 先验证「不伤标称」。②专家坍缩（总用同一专家）→ 负载均衡损失 + 硬路由只在置信高时启用。③**合规**：条件专家是否仍算「同一模型」必须书面确认（PR7）；确认前不上计分通道，保留纯基座回退。④每端口不同门控导致 adapter 无法全局合并 → 用加权 LoRA 或按门控聚类分组（见 I11）。

### I11 多机协同服务编排（新） ★★★★

- **动机**：N 台机器人随机顺序评测、每台固定端口（F22）；单模型规则（F21）与大模型体积（F26）使得「N 份独立进程」不经济。需要一个共享后端，把 N 条异构 episode 流服务好，同时保证状态隔离与延迟公平。
- **与现有方案差异**：官方 README 的 Approach 2 只说了「共享一个模型 + 请求分发 + 状态隔离」，没有调度策略；本点把 **chunk 感知的截止期、跨端口动态微批、专家缓存/分组、公平性** 形式化并做压测。
- **设计**：
  1. **端口层**：每端口一个轻量 websocket 端点 + `EpisodeState`（观测历史、chunk 游标、路由门控、检索先验、I4 干预状态）；端口间不共享可变状态。
  2. **调度层**：每次请求带 `deadline = now + control_period × T_a − margin`；调度器在等待窗口 $W$ 内收集请求，按「最紧截止期 + 同专家分组」组成 micro-batch；长 chunk 端口可被判定为「睡眠」让出 GPU。
  3. **专家层**：reset 期确定门控后，将加权 LoRA 预合并为该端口的等效 adapter（或按门控聚类分组），常驻显存；per-step 只做固定 adapter 前向。
  4. **稳定性**：单请求快速路径（N 小或请求稀疏时不做批）；背压与队列上限；超时降级为短 chunk；健康探针 + 端口就绪检查。
- **技术可行性**：中-高。纯服务工程 + 排队论；N 未公布，按 $N\in\{1,2,3,5,8\}$ 做包络压测；用 stub 客户端即可离线验证，不耗真机。
- **所需资源**：1×A100 80G 可承载 6B bf16（12.46GB）+ 专家 + 激活，N≤3；2×A100 用于 N=4–5 或留延迟余量。工程 1–2 人周。
- **落地步骤**：①端口管理器与状态隔离单测（并发 reset 不串）；②共享后端；③截止期 micro-batch；④专家缓存/预合并；⑤回放压测（chunk ∈ {1,8,16,30} × N × 任务混合）；⑥p99/吞吐/公平报表进 I8 注册表。
- **风险**：①异构 batch 增加 p99 → 限制 batch 上限、按 deadline 切分、保留快速路径；②N 很小或 chunk 很大时批处理收益≈0 → 此时 I11 退化为「共享权重 + 隔离状态」的保守实现，不强行批；③端口数必须精确等于 N（F22），多开/少开都可能被拒 → 用启动自检；④跨端口状态污染是最致命 bug → 每次并发测试都做「端口间输出独立性」回归。

### I12 双臂共享潜变量协同（新） ★★★★

- **动机**：双手协调是官方三大能力维度之一（F21）；数据含双臂与 lower_body（F27），但单臂任务也带闲置臂轨迹。多数队伍只学主动臂，闲置臂漂移会触发失败/异常动作；双手任务若用两个独立单臂头，两手会互相打架。
- **设计**：
  1. **手臂使用审计**：用 32 个数据集统计每任务左右臂关节能量、gripper 活动、EE 位移，得到「左/右/双臂」标签；先确认哪些任务真正需要双手。
  2. **角色路由**：由语言 + 首帧预测 `role ∈ {left, right, bimanual}`；单臂任务把非主动臂锁在 reset 时的位姿（输出 hold），并做限幅/平滑。
  3. **共享潜变量 + 一致性**：双臂任务用共享 latent $z$ 分头解码两手，增加相对位姿一致性损失与时间同步损失：

$$
\mathcal{L}_{\text{coord}}=\lambda_1\big\|(T_L^{-1}T_R)-(T_L^{-1}T_R)^{\text{demo}}\big\|^2+\lambda_2\|\dot{T}_L-\dot{T}_R\|^2 .
$$

  4. **安全**：锁臂不能锁错——只有语言与视觉证据一致时才锁；否则退化为双臂都活跃。
- **可行性**：中。无需新数据（双臂标注已有）；主要成本是数据审计 + 损失实现 + 训练。
- **所需资源**：1×24GB LoRA 增量训练；审计 2–3 人日；无新下载。
- **落地步骤**：①32 任务手臂审计表；②闲置臂锁定基线；③共享 latent/一致性损失；④L0：标称不掉点 + 双手任务相对位姿误差下降 + 闲置臂漂移下降；⑤L2 双手任务抽测。
- **风险**：①角色误判锁错臂 → 软门控 + 双证据一致才锁；②双臂任务占比未知，收益可能集中在少数任务 → 先审计后投入；③一致性约束过强会限制单手灵活操作 → $\lambda$ 从 0 退火，L0 找拐点。

class MacroBalancedSampler:            # 取代官方 ConcatDataset 的样本比例采样（F25）
    def sample_task(self):
        g = rng.choice(list(P_GROUP), p=list(P_GROUP.values()))
        pool = CHALLENGE_32 if g == "challenge" else self.available[g]
        if g == "challenge":
            return rng.choice(pool)    # 32 任务等概率

    def sample_episode(self, task):

        w = np.array([0.2 + 0.8 * self.quality[t][e] for e in eps])
        return rng.choice(eps, p=w / w.sum())   # 质量加权仍在任务内

def macro_train_step(batch):
    # batch 至少覆盖 2 个技能族，才能做梯度手术
    losses = [task_loss(batch[g], family_head[g]) for g in batch.groups]
    grads = [torch.autograd.grad(losses[i], shared_params, retain_graph=True)
             for i in range(len(losses))]
    grads = [pcgrad_project(grads[i], [grads[j] for j in range(len(grads)) if j != i])
             for i in range(len(losses))]
    apply_sum(grads, shared_params)

class FactorizedPolicy:
    def reset(self, obs0, lang):                 # 每 episode 恰好一次（F18）
        f = fuse(vlm_pool(obs0), text_embed(lang), retrieval_feat(obs0, lang))  # I9 特征

        self.beta  = self.eps_axis  * self.g_axis

### 2.3 截止期感知的多机 micro-batch（I11）

```python
class MultiPortScheduler:
    def submit(self, port, req):
        T_a = state[port].action_chunk_size
        budget = control_period * T_a - safety_margin
        self.q.push(port, req, deadline=now() + budget)

    def collect(self):
        # 在等待窗口 W 内收集；优先最紧截止期，再按等效 adapter 分组
        cand = self.q.pop_due(now() + W)
        return group_by(cand, key=lambda r: state[r.port].adapter_id, max_bs=B)

    def loop(self):
        while True:
            batch = self.collect()
            if batch:
                self.backend.infer(batch)   # 共享 f_theta，只读权重
            self.enforce_isolation()        # 断言各 port 的 EpisodeState 不相交
            self.report(p99, throughput, fairness)  # 进 I8 注册表
```

### 2.4 双臂协同（I12）

```python
class DualArmPolicy:
    def reset(self, obs0, lang):
        self.role = role_head(obs0, lang)        # left / right / bimanual
        self.hold = {arm: obs0[f"state.{arm}_ee_pose_gripper_base"] for arm in ("left", "right")}

    def act(self, obs):
        z = self.shared_latent(obs)              # 双臂共享潜变量
        aL, aR = self.dec_left(z), self.dec_right(z)
        if self.role == "left":   aR = hold_action(self.hold["right"])
        if self.role == "right":  aL = hold_action(self.hold["left"])
        return aL, aR, self.coord_loss(z)        # 一致性损失见 §1 I12
```

|---|---|---|---|
| L0 | ①I2 v3 分层采样分布单测；②迁移矩阵（32×110 子集，代理指标）；③I10 五种路由消融；④I12 手臂审计 + 闲置臂漂移；⑤I11 N 端口回放压测 | 离线（免费） | 采样频率≈1/32；迁移矩阵无家族级显著负迁移；I10 标称宏平均≥基座且 worst-k 提升；I12 双手任务相对位姿误差↓；I11 p99 在预算内 |

| 检索库 | 嵌入 1×GPU 日 + FAISS（I9） | 复用为 I10 路由特征 |
| 人力 | 数据/增广 1、训练 1、serving 1、评测 1 | 新增 serving 压测工作量 |

## 5. 伦理合规 checklist（更新）

- [ ] **单模型边界（本轮最高优先）**：I10 的条件专家是否仍算「同一模型」、I11 的多端口是否只是同一模型的多个服务实例、I9 reset 检索是否合规——均须向组委会书面确认；确认前不上计分通道（PR7）。
- [ ] 不在评测时段做任何在线学习/权重更新/跨 episode 适应；reset 检索与路由都是**推理期计算、零权重更新**，episode 内缓存。
- [ ] 端口状态隔离：并发测试中验证端口 A 的 reset/历史/门控不会影响端口 B；端口数严格等于 N（F22）。
- [ ] 人手在场 → 降速/停持/让位（PR3）；双臂场景避免锁臂时夹到人手。
- [ ] 动作健康度（界内/平滑/统计正常）为每次提交的 PR4 门禁；大 chunk 下尤其要检查 chunk 边界跳变。
- [ ] 数据使用：官方数据集（32 任务 + 110 语料 + DiverseManip，apache-2.0）许可内使用，共训注明来源；`DualRobot` 只作先验。

## 7. 本轮最值得押注（一句话）

**押「宏平均对齐的多任务因子化 + 单模型多端口调度」：I2 v3 先把训练分布按 32×5 网格摆正（下限），I10 用零初始化软路由把「共享技能 / 隔离冲突」显式化（上限），I11 用一个共享后端把 N 条异构流服务好（稳定性）；数据对齐决定分数下限，路由与调度决定上限。**

## 8. 本轮最大风险（一句话）

**把「多机协同/多任务」做成一层不确定的复杂路由与调度——若组委会对「单模型」的解释不允许条件专家、或 N 很小/大 chunk 使并发批处理无收益、或轴路由在 reset 首帧上不可靠，I10/I11 就会从增益变成纯开销；因此必须先用 L0 消融与书面合规确认给这两点设止损，且把 I10 设计成零初始化残差、默认退化为基座模型。**
