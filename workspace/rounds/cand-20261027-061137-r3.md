# 第 8 轮（灵感循环第 3 轮）· KINE-EXEC：运动学是最后一公里的操作系统，实时控制是它的时钟

> 检索/复核日期：**2026-10-27（UTC）**。赛事身份确认不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「运动学」「创新点提炼」「实时控制」。轮次说明：状态文件上一轮为第 7 轮 PILOT，本轮顺延为第 8 轮；按用户口径是灵感循环第 3 轮。
>
> **主判断：榜首不到 30% 的共享瓶颈，不是“看不懂”，而是“最后 3 厘米的关节空间执行”。** 我们对官方数据的两个分片做了 FK/限位/IK 审计：PlugCharger 左臂有 **74.4%** 的帧把 `wrist_yaw` 用到限位 10% 以内、**49.1%** 的帧用到 5% 以内；右臂也有 43.9%/8.3%；肘屈曲 p95 达 **163°**，swivel 圆半径 p5 只有 **1.95cm**。这不是某个模型的问题，而是演示本身就在运动学边界上工作；策略只看到笛卡尔目标，7-DOF 冗余被低层 IK 隐式处理，OOD 一扰动就没有余量。与此同时，API 的 chunk 是**整段执行**的，WLA 默认 30 步@30fps = 1s，接触段的反馈频率只有 1–4Hz。**最值得做的不是第 14 个语义模块，而是给冻结 VLA 套一层“运动学执行层”（KINE-EXEC）：KRA 把 EE 目标编译成可行、留余量、示范条件化的关节轨迹；DAC 把 chunk 编译成延迟感知、C1 连续、末端安全的时间参数化轨迹；KRM 在 chunk 边界用关节残差、限位余量和可操作度做接触/卡住/撤销检测与恢复。** 这也是对上轮“放置是闸门”的深化：放置目标选对了，最后一公里仍可能因为关节限位、奇异构型或 chunk 延迟而失败。

### 0.2 规则：成功率第一，320 trials，步骤分只是 tie-break

官方参赛手册（[S4][S5]）明确：

```text
排名：32 任务总平均成功率 > 总平均步骤分 > 提交日期
每个任务 10 次 = 5 类泛化（位置/干扰物/背景/未见物品/人为干扰）× 2
32 × 10 = 320 个计分 episode；单次最长 180s；超时失败
仅通才单模型赛道；不计分单任务调试通道只用于自测
```

这条决定了本轮的目标函数：**只做能提高整任务成功率的组件**；步骤分只用于诊断和平局裁决。KINE-EXEC 的三个组件都必须能落到“整任务成功”上，而不是只让轨迹更漂亮。

### 0.3 API：joint/EE 互斥、chunk 整段执行、没有腰动作、没有力/触觉

`unibot_submission` README（[S6]）与本地 stub（[S7]）给出：

- 观测：4 路 RGB 480×640、双臂 7 维关节、双臂 EE pose（base 系）、夹爪开度、`lower_body`[15]、单条 `language`；**没有力矩/触觉/电流/深度**。
- 动作：`control_space` 只能 `"joint"` 或 `"ee"`，互斥；joint 模式返回 `action.left_arm`[7]/`action.right_arm`[7]；ee 模式返回 `action.left_ee_pose_gripper_base`[6]/right[6]；两者都必须返回 `action.left_gripper`[1]/`action.right_gripper`[1]/`action.pivot`[7]。
- `action_chunk_size` 固定；`get_action` 返回一个 chunk，evaluator 先执行 index 0，再顺序执行其余，直到下一次调用。**没有真正的 mid-chunk 异步**，chunk 边界是唯一闭环点。
- 观测帧率/延迟由 evaluator 记录；官方会看延迟稳定性。N 个连续端口（官方指定），每端口独立进程/状态（[S6]）。

### 0.4 `action.pivot` 不是腰：它是一个 base（底盘）+ 高度命令

这是本轮最重要的接口纠偏。官方数据集的 `action.pivot` 字段名是 `[vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]`；我们直接对比了两个分片（[S8][S9]）：

| 检查 | 结果 |
|---|---|
| `pivot[0:3]` vs `action.base_command[0:3]` | 逐帧完全相等（max diff = 0） |
| `pivot[6]` vs `action.base_command[3]`（height） | 逐帧完全相等（max diff = 0） |
| `pivot_3` / `pivot_4` / `pivot_5` | HangCup 与 PlugCharger 全是常量 **0 / 0.15 / 0** |
| `pivot_3..5` vs `waist_state_joint` | 无相关；腰状态在动，pivot 后三维不动 |
| `action.waist_action_joint` | 数据集里有 [3]，但**提交 API 的动作目录没有这个键** |

结论：**`action.pivot` 是“底盘 base + 高度”的低层命令，不是 3-DOF 腰；后三维可能是步态/站姿参数，但语义未公开。API 只暴露腰的观测（`lower_body` 的后三维），不暴露腰的动作。** 因此：

- “用 3-DOF 腰做宏冗余”在本赛 API 下**不可直接部署**；它只能作为离线可达性上界和诊断量。
- 腰在演示里确实会小幅运动（std 约 0.02–0.04 rad），但 API 不暴露腰动作；它只能作为观测到的基座变换，不是策略可写变量。KRA 必须在 FK 中把它当**已观测的准静态基座变换**，不能把它当自由变量。
- `pivot_3..5` 在两个任务里都是常量；它们很可能是步态/站姿参数（语义未公开），但不是关节目标。

### 0.6 平台是 29-DOF G1：7-DOF 臂 + 3-DOF 腰；但动作空间只给臂

- G1 EDU 29-DOF：**每臂 7 DOF、腰 3 DOF、每腿 6 DOF**（[S11][S12]）。挑战数据用 7-DOF 臂 + 3-DOF 腰；URDF `g1_29dof_rev_1_0.urdf` 给出完整关节限位（[S13]）。
- 数据集 `lower_body`[15] = 12 腿 + 3 腰；`waist_state_joint`[3] 单独存在；`action.lower_body`[15] 与 `action.waist_action_joint`[3] 也在数据里。
- 但提交 API 的动作只有双臂 + 夹爪 + `pivot`[7]；**没有 `action.lower_body` / `action.waist_action_joint`**。所以策略能“看见腰”，不能“命令腰”；腰的动作不在策略接口内，具体由官方低层/评测栈处理（未公开）。
- 这使本轮的主战场从“臂 + 腰”收缩为“**臂的 7-DOF 冗余 + chunk 时序**”。腰只作为 FK 的已知变换和离线上界。

### 0.7 WLA-1.0-Base：6B、30-step、相对 EE、3 相机；与 API 有表示差

- UnifoLM-WLA-1.0-Base：**6B** 参数、Apache-2.0、约 2,500h 真机数据、64 任务；支持 LoRA/action-expert 微调（[S14][S15]）。
- 默认数据配置 `chunk_size: 30`（30fps 下约 1s）、`target_fps: 30`、图像 336×448；动作是 **相对当前 EE 的 SE(3)**，不是绝对 base 系位姿；训练用 3 路图（head left + 左右腕），不是 4 路（[S15]）。
- 统一动作是 54 维，含左右 EE、夹爪、腰、torso、base、腿；挑战 API 只接受臂 + 夹爪 + pivot。**模型能输出腰/腿，但 API 会忽略/拒绝这些键**；我们必须在 adapter 里 mask 掉，并在挑战数据上微调 action expert。
- 这给出一个明确的工程任务：**WLA 相对 EE chunk → 绝对 EE → KRA IK → 绝对关节 chunk**。EE 模式则只需相对→绝对；两种都可，但 joint 模式才能让 KRA 和 KRM 掌握冗余与残差。

### 0.8 实时控制：chunk 整段执行，闭环频率是设计变量

- RTC（[S16]）把异步 chunking 形式化为 inpainting：在执行当前 chunk 时生成下一个，冻结“保证会执行”的前缀；REMAC（[S17]）用 masked action chunking 处理延迟；Action Chunk Scheduling（[S18]）指出多机器人服务时“chunk 太长会失去反应性、太短会饥饿”。
- 本 API **不允许真异步**：evaluator 执行完整个 chunk 才再次调用。所以 RTC 的“执行中推理”不能照搬；能做的是**延迟感知的 chunk 编译**：
  - 平均观测年龄 ≈ `L + T/(2*30)`，占空比 ≈ `T/(T+30L)`（L 秒，T 步，30Hz）。
  - 相同 L 下，T 越短，年龄越小、反应越快，但推理次数越多；T 越长，越平滑、越省算力，但接触段越“盲”。
  - 表（L=100/200/300ms，T=2/4/8/16/30）见 §1.3；结论：接触任务目标年龄 <200ms；L=100ms 时 T=2–4，L=200ms 时 T=2–4 也很勉强，L=300ms 必须做模型加速或接受慢接触。
- 180s 预算允许“慢而稳”的接触，但 human 轴（20% trials）需要一定反应性；所以 chunk size 不能盲目用 30，建议从 **T=4–8** 起测，接触段用 terminal-safe chunk。

## 1. 三个词，各自钉到可落地模块

### 1.1 运动学：演示自己在限位上，冗余没有被显式使用

#### 1.1.1 FK 标定：先解决“数据陷阱”

我们用官方 `g1_29dof_rev_1_0.urdf` 实现 FK，并和数据集 `observation.state.*_ee_pose_gripper_base` 对齐（[S13][S8][S9]）：

| 检查 | 结果 |
|---|---|
| 躯干 FK vs `state_torso` | 完全吻合 |
| 手臂 FK vs EE（按 URDF 顺序映射） | 位置残差 std **1.14mm（HangCup）/0.98mm（PlugCharger）**，姿态残差 0 |
| 按 parquet 字段名直观映射 | 位置误差约 **10cm**（腕部三轴顺序错） |
| 工具偏移 | gripper base 相对 palm 约 **6.65cm**（沿 palm x）；加上后残差 std ~1mm |

**关键陷阱**：parquet 的 `names` 写的是 `shoulder_pitch, shoulder_roll, shoulder_yaw, elbow, wrist_yaw, wrist_roll, wrist_pitch`，但数值实际按 URDF 的 `wrist_roll → wrist_pitch → wrist_yaw` 排列。也就是说，**字段名第 5–7 位与数值第 5–7 位是错位的**。任何按名字直接喂关节的模型都会学到错标签；这可能是 joint-space 策略表现差的一个被忽视的原因。

**第二个陷阱**：API 的 `action.left_arm`[7] 没有给关节名；数据集的数值顺序是否等于 API 的顺序，官方没有写。**在真机调试槽里必须先做关节顺序标定**（小幅单关节运动 + 观测 EE/关节响应），否则 joint 模式可能把 wrist_yaw 命令发到 wrist_roll。标定前，EE 模式更安全；标定后，joint 模式才可用。

#### 1.1.2 限位审计：PlugCharger 是“贴着腕限位”的任务

关节限位余量定义为 `min(q-q_min, q_max-q)/ (q_max-q_min)`。`wrist_yaw` 的范围是 ±1.614 rad（总 3.228 rad），所以 **5% = 0.161 rad = 9.2°**，10% = 18.5°。

| 任务（分片） | 帧 / episodes | 左腕 yaw <10% / <5% | 右腕 yaw <10% / <5% | 任一关节 <10%（L/R） | 肘屈曲 p95 | per-episode swivel span p50 | swivel 半径 p5 |
|---|---:|---:|---:|---:|---:|---:|---:|
| HangCup file-001 | 63,999 / 324 | 0.9% / 0.1% | 3.0% / 0.1% | 2.8% / 7.3% | 88.3° | 29.2° | 9.17cm |
| PlugCharger file-003 | 70,910 / 169 | **74.4% / 49.1%** | **43.9% / 8.3%** | **74.9% / 44.2%** | **163.5°** | 46.0° | **1.95cm** |

读法：

- PlugCharger 左臂近一半的帧，腕 yaw 距离限位不到 **9.2°**；这不是偶发，而是任务的主构型。HangCup 则是弯肘、较大 swivel 半径的构型。
- 肘屈曲 p95 **163°**（接近伸直）+ swivel 半径 p5 **1.95cm**，说明 PlugCharger 在接近全伸展/低可操作度的区域工作；这是插入任务需要“往里推”的几何后果。
- **不同任务处于不同运动学 regime**：全局一个 IK 先验会互相伤害；KRA 必须按任务/相位条件化（SSG 的步骤标签正好可用）。

#### 1.1.3 IK 零空间：臂的余量有限，腰的上界不可部署

在 12 个 `wrist_yaw` 饱和帧上，用 40 个随机种子做 arm-only IK（7 变量，6D 目标；[S19]）：

- 多数帧 40/40 成功；有一帧只有 **12/40** 成功，说明有些目标在臂的限位/奇异边界上确实很难。
- 可行替代解的 `wrist_yaw` 最大余量：**2.1%–10.0%**（中位 0.0%–3.7%）；关节重构 p50 0.08–0.54 rad。
- 加 3-DOF 腰（离线）后：12/12 帧 **40/40** 成功，最大余量 **5.5%–18.0%**，腰动 ~0.17–0.27 rad，臂重构 0.4–0.6 rad。
- **但腰不可命令**（§0.4），所以这组腰数据只能作为“如果腰能动，上限在哪”的诊断；**不能进主路径**。

这给出一个现实的预期：arm-only KRA 不能把余量从 0 变成很大，但能把“贴着限位”变成“有 2–10% 余量”，并把关节重构控制在 ~0.1–0.5 rad。对于 OOD 位置/未见物体，这几度到十几度的余量可能就是从失败到成功。

#### 1.1.4 工具偏移放大姿态误差

gripper base 相对 palm 的 6.65cm 偏移意味着：绕垂直于工具轴的 1° 姿态误差 ≈ **1.16mm** TCP 误差；5° ≈ **5.8mm**；10° ≈ **11.6mm**。而插入/堆叠的容差常常就是 1–5mm。**腕部限位导致的“保位置、丢姿态”会直接变成 TCP 误差**；KRA 必须在零空间里优先保姿态和腕部余量，而不是只保位置。

### 1.2 创新点提炼：从 13 个点压缩到 3 个核心下注

上一轮清单有 13 个组件（SSG/PGL/OPT/ICR/SVL/NRB/L2L/DebugLoop/GPR/TLE/AH-TP/TCLB/FLEET），问题不是“不够多”，而是**语义、数据、部署混在一起，没有对准“执行”这个共享瓶颈**。本轮的评分表：

| KRB 运动学回放台 | 评测 | — | 高 | 低 | 1 周 | 工具（go/no-go） |

| SSG 评分步骤图 | 中 | 高 | 高 | 低 | 1 周 | 保留为相位层 |

| 闭合/拉链 | T19 ZipUp（50）、T23 StorePaddle（50）、T31 OrganizePencilCase（40）、T18 PackBag（25）、T28 StoreEarphones（25） | 低速度高力矩、残余运动、卡住/回退 |
| 可变形 | T16 FoldTowel（20）、T17 OrganizeStationery（20）、T30 RemovePinnedNote（50） | 慢速、力代理、阶段切换 |

### 1.3 实时控制：chunk 是整段执行的，闭环频率是设计变量

把延迟写成设计公式（L 秒，T 步，30Hz）：

```text
平均观测年龄  age ≈ L + T/(2*30)
执行占空比    duty ≈ T/(T + 30L)      # 机器人“有动作可执行”的时间比例
```

| L | T=2 | T=4 | T=8 | T=16 | T=30 |
|---:|---:|---:|---:|---:|---:|
| 100ms | 133ms / 40% | 167ms / 57% | 233ms / 73% | 367ms / 84% | 600ms / 91% |
| 200ms | 233ms / 25% | 267ms / 40% | 333ms / 57% | 467ms / 73% | 700ms / 83% |
| 300ms | 333ms / 18% | 367ms / 31% | 433ms / 47% | 567ms / 64% | 800ms / 77% |

读法：

- 接触任务的目标是 **age <200ms**；L=100ms 时 T=2–4 可以，T=30 不行（600ms）。
- L=200ms 时，T=2–4 仍然 233–267ms；只能靠“慢动作 + 螺旋搜索 + 力代理”而不是快速闭环。
- L=300ms 时，任何 T 都 >300ms；必须做模型加速（蒸馏/小 action expert/缓存）或接受接触段是半开环。
- 180s 预算允许慢，但 human 轴要求一定反应性；**T=4–8 是折中起点**，接触段用 terminal-safe chunk（最后一个动作是“停住/保持”，不是快速运动）。

**terminal-safe chunk**：因为 evaluator 会执行整个 chunk，且下一次调用可能延迟，chunk 的末尾必须是安全动作。具体：把 chunk 的后 1–2 步设为目标保持/轻微回撤/夹爪保持，而不是继续快速下压。这样即使下一次观测晚到，机器人也不会冲过头。

**C1 拼接**：在 chunk 边界，用当前关节/EE 状态对下一 chunk 做位置和速度对齐；如果模型输出的是绝对目标，用“当前状态 + 模型增量”而不是“模型绝对目标”来避免边界跳变。RTC/REMAC 的证据说明边界 jerk 是失败源；我们没有真异步，但可以做边界 C1。

**接触搜索原语**：插入类任务在视觉对齐后，用小幅螺旋/抖动 + 轴向慢推 + 关节残差检测“卡住/滑入”。这是经典 peg-in-hole 的无传感器策略（[S20]），但这里用**关节跟踪残差**替代力觉：当命令继续下压而关节/EE 不再前进，残差变大，说明接触；当残差突然回落，说明插入/滑入。KRM 负责这个判断。

## 2. 主判断：KINE-EXEC

```text
语言 → SSG 相位/步骤（保留）
     → PGL/OPT 目标位姿（保留，作为“做什么/放哪里”）
     → 冻结 VLA（WLA/EE）→ 相对 EE chunk
     → KRA：绝对 EE → 7-DOF 关节目标（限位/奇异/自碰撞/双臂约束/示范先验）
     → DAC：时间参数化 + 延迟补偿 + C1 拼接 + terminal-safe + 接触原语
     → joint chunk（API）
     → KRM：关节残差 / 限位余量 / 可操作度 / 相位 → 恢复（下一 chunk）
     ↑______________________ KRB 离线标定与回归 ______________________|
```

### 2.1 KRA：运动学冗余适配器（核心）

**问题**：VLA 输出 6D EE 目标；机器人有 7-DOF 臂（每臂 1 个冗余 DOF），但低层 IK 可能选一个贴着限位/奇异的解。我们要在**不改变 EE 目标**的前提下，选一个留余量、平滑、接近示范的关节解。

**约束**（每个控制 tick 解一个小 QP/阻尼最小二乘）：

```text
min   ||J dq - e||^2_W  + λ1 ||dq||^2 + λ2 ||q - q_demo||^2 + λ3 ||q - q_center||^2
s.t.  q_min + m <= q <= q_max - m          # 限位余量 m，例如 5% 行程
      |dq| <= dq_max                        # 速度限
      |ddq| <= ddq_max                      # 加速度限（用上一条命令差分）
      sigma_min(J) >= sigma_eps             # 奇异回避（软约束）
      d(q, self) >= d_safe                  # 自碰撞（可选，胶囊体）
      ||p_L - p_R - d_rel|| <= eps_bimanual # 双臂相对位姿（可选）
```

**零空间目标**（关键，不是简单“回中”）：

- **限位余量**：对接近限位的关节加排斥势，优先把 `wrist_yaw` 从 5% 推到 10% 以上。
- **可操作度**：`sqrt(det(J J^T))` 或 `sigma_min`；PlugCharger 的 swivel 半径 p5 只有 1.95cm，需要避免继续靠近奇异。
- **示范条件化**：用同任务/同相位的演示关节分布做先验；不是复制轨迹，而是“在这个相位，肘/腕大致在哪个 regime”。HangCup 的弯肘 regime 与 PlugCharger 的伸展 regime 不能混。
- **双臂相对位姿**：T26/T05/T18 等双臂任务，保持两手相对位姿/角色分配；用软约束，避免硬约束导致 IK 不可行。
- **平滑**：`||dq||^2` 和 `||q - q_prev||^2`，避免 chunk 内抖动。

**信任域**：KRA 不应偏离低层 IK 太远。以低层 IK 解或演示解为中心，限制 `||q - q_ref|| <= r`（例如 0.3–0.5 rad）；如果为了余量需要更大重构，标记为“高置信度下降”，让 KRM/策略决定是否接受。这样避免 KRA “为了余量把任务几何搞坏”。

**输出**：绝对关节目标 chunk（7×2 + grippers），与 API joint 模式对接。KRA 是确定性代码，不是第二个模型；符合单模型规则。

### 2.2 DAC：延迟感知 chunk 编译器（核心）

**问题**：chunk 整段执行，模型推理有延迟；接触段需要高反馈频率；chunk 边界容易 jerk。

**设计**：

1. **延迟测量**：每个 chunk 记录 `t_request → t_response`；用滑动 p50/p95 估计 L。初始 L 用离线压测/官方记录。
2. **chunk size**：根据 L 和任务相位选 T；但 `metadata.action_chunk_size` 在 handshake 固定，所以只能选一个全局 T（建议 4–8），或返回固定 T 但在内容上做“有效 horizon”变化。
3. **时间参数化**：把模型输出的离散 EE 路点拟合成 min-jerk/三次样条，限制速度/加速度/ jerk；在接触段降低速度。
4. **C1 拼接**：用当前状态对齐下一 chunk 的起点；位置连续 + 速度连续；不要把模型的绝对目标直接跳过去。
5. **terminal-safe**：chunk 末尾 1–2 步为保持/回撤/夹爪保持；防止晚到观测导致冲过头。
6. **接触原语**：插入类任务在最后 1–2cm 用螺旋/抖动 + 轴向慢推；用 KRM 的残差决定继续/回退。
7. **可选加速**：如果模型 server 可改，缓存 VLM latent / 复用 action expert（视觉变化慢时）；这是工程优化，不是新模型。

**为什么不是 RTC**：RTC 需要“执行当前 chunk 时生成下一个”，本 API 的 evaluator 是同步调用，不能并发。我们可以借鉴它的“冻结前缀 + inpaint 其余”思想，但落地为“边界 C1 + terminal-safe + 延迟感知 T”，而不是真异步。

### 2.3 KRM：运动学残差监控与恢复（核心）

**问题**：没有力/触觉；接触、卡住、滑脱、限位、撤销只能从本体感觉 + 动作推断。joint 模式给了我们一个独特优势：**命令关节和观测关节的差是直接可见的**；EE 模式下低层 IK 会把这个差吃掉。

**特征**（每个 chunk 边界计算）：

- `r_q = q_obs - q_cmd`（关节跟踪残差），以及 `J(q) r_q` 投影到任务空间。
- `r_ee = FK(q_obs) - EE_cmd`（EE 残差）。
- 限位余量 `m(q_obs)`、可操作度 `sigma_min(J)`、`|dq|`、`|ddq|`。
- 夹爪开度/命令差、相位（SSG）、视觉变化（可选）。
- 历史窗口的残差均值/方差/斜率；chunk 边界的残差跳变。

**判断**：

- **接触/卡住**：命令继续沿某方向，但 `r_q` 在该方向持续增大、速度接近 0；或 `r_ee` 不跟随。PlugCharger 插入段的残差是强信号（前轮数据：AUROC 0.866），轻物体（HangCup）弱（0.722），所以必须结合相位/夹爪/视觉。
- **限位**：`m(q_obs) < 5%` 且 `r_q` 在限位方向饱和；触发 KRA 的零空间重选或回退。
- **滑脱/掉落**：夹爪开度突变 + EE 残差/视觉下落；触发重抓。
- **撤销/人为干扰**：SSG 谓词从 1→0，或目标物体位置突变；触发回退/重做。
- **正常**：残差在标定阈值内，继续。

**恢复原语**（下一 chunk 执行，不 mid-chunk）：慢速回退 1–3cm、重试接近、螺旋搜索、重抓、换手（双臂任务）、请求 KRA 换构型。每个 episode 限制次数，避免 180s 超时。

**阈值**：用成功演示的残差分布做 conformal/分位数阈值（例如 p99），按任务/相位分桶；不训练第二个模型。KRM 是确定性监控 + 统计阈值，符合单模型。

### 2.4 KRB：运动学回放台（评测工具）

**目的**：在不上真机的情况下，回答“KRA/DAC/KRM 是否值得上真机”。

**数据**：官方 33k 演示 + 两个已下载分片；每个任务采样 50–100 episodes。

**实验**：

1. **FK 校准**：用 URDF FK 对 `state_torso`/EE 做残差检查；确认关节顺序/工具偏移。
2. **IK 回放**：取演示 EE 轨迹，用 KRA 重解关节；比较重解关节 vs 演示关节的 TCP 误差、姿态误差、限位余量、可操作度、关节重构。
3. **扰动压力测试**：对 EE 目标加 ±1/2/5cm 平移、±2/5/10° 旋转（模拟 OOD 位置/未见物体），测 IK 成功率、余量、是否撞限位。
4. **延迟注入**：用 T=2/4/8/16/30 和 L=50/100/200/300ms 重放，测跟踪误差、边界 jerk、有效占空比。
5. **残差可分性**：用演示中的接触/非接触段，测 KRM 特征的 AUROC/TPR@5%FPR；按任务分桶。
6. **配对统计**：同一 episode 的 KRA vs baseline，用配对 bootstrap；报告 95% CI。

**Go/No-Go**：

- KRA：IK 回放成功率 ≥95%，TCP 误差 ≤2mm，姿态误差 ≤1°，限位违规 <1%，在饱和帧上 margin 提升 ≥5% 的帧占比 ≥50%。
- DAC：边界 jerk 降低 ≥50%，延迟注入下跟踪误差不劣于 baseline 10% 以上。
- KRM：接触/卡住 AUROC ≥0.8，误报 <10%，恢复成功率 ≥50%（离线模拟）。
- 任一不达标 → 不上真机，回退/改设计。

## 3. 预期收益、可证伪与统计功效

### 3.1 预期收益

- **KRA**：在 PlugCharger/T26/T05 等限位/插入任务上，把“贴限位”变成“有 5–10% 余量”；目标单任务 +10–20pp；对 OOD 位置/未见物体更稳。
- **DAC**：减少 chunk 边界 jerk/过冲；目标接触任务 +5–15pp；对 human 轴的反应性提升。
- **KRM**：卡住/滑脱/撤销的恢复；目标 +5–15pp，主要救“差一点成功”的 episode。
- **总目标**：+2–4pp 总分（32 任务平均），其中 5–8 个接触富任务 +10–20pp；保守目标 +2pp。

### 3.2 可证伪

- 如果 KRB 上 KRA 的 IK 成功率 <90%，或饱和帧 margin 提升 <2%，则 KRA 假设不成立 → 砍。
- 如果延迟注入下 DAC 不能把边界 jerk 降低 30%，或 T=4–8 的跟踪误差比 T=30 更差，则 DAC 假设不成立 → 回退到 T=8–16。
- 如果 KRM 的接触/非接触 AUROC <0.75，或误报 >15%，则 KRM 不能上真机 → 只做诊断。
- 如果调试槽里 T10/T27 的终局步提升 <5pp，则执行层不是主瓶颈 → 回到目标层（PGL/OPT）。

### 3.3 统计功效

- 320 trials，p≈0.3 时总体 SE ≈ **2.56pp**；单任务 10 trials，SE ≈ **14.5pp**；单轴 64 trials，SE ≈ **5.73pp**。
- 独立两比例 80% 功效约需 **10pp** 差异；配对设计（同场景/同初始状态）约需 **7pp**。所以：
  - 不要用 1–2pp 的官方跑差异判断方法好坏；
  - 调试槽必须追求 **+15–20pp** 的大效应，否则是噪声；
  - KRB 离线配对 + bootstrap 是主 go/no-go，官方跑是终局确认。

| 风险 | 概率 | 影响 | 缓解 | 停止条件 |
|---|---|---|---|---|

| 外部数据/合作违规 | 低 | 高 | 本轮不用外部数据；KRB 只用官方 33k | 规则禁止 → 砍 L2L |

**合规要点**：

- KINE-EXEC 不引入第二个学习模型；IK/QP、时间参数化、阈值监控都是确定性算法。
- 不使用外部数据、仿真 RL、每任务 LoRA；WLA 微调只用官方数据。
- 模型卡披露：唯一 checkpoint（WLA + LoRA/action expert）、KRA 的 URDF/参数、DAC 的 chunk/延迟参数、KRM 的阈值来源。
- 调试槽只做发布门，不做日常调参；每个大版本最多 1 槽。

### 0.3 预期收益（可证伪）

### 1.1 榜单与规则

**榜单**（检索 2026-10-27，[S1][S2][S3]）：

- `leaderboard.html` 现在能渲染 8 个模型；顶部写 `Ranking · Live`，但底部仍写「即将发布」。
- `leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`；8 模型 × 32 任务 = 256 条 `task_metrics` 是脚本生成。
- `runs.html` 仍是 256/256 条记录，详情页视频为占位。
- 预览 top：MolmoAct2/DexHacker **29.7% / 39.0**；WALL-OSS-0.5 28.5/38.9；DreamZero 27.9/37.9；Spirit-v1.5 25.9/34.4；DM0 23.5/31.7；PI-0.5 22.8/30.6；GigaBrain-0 22.6/29.5；GR00T N1.5 20.5/28.1。

**结论**：用户说的“榜首不到 30%”与预览 top 29.7% 吻合；但这不是已发布真实排名，只能当难度/模型家族先验。任何“某任务只有 21.3% 所以最难”的论断都要加“若数字为真”。

**规则**（[S4][S5]）：

```text
32 任务；每任务 10 次 = 5 类泛化（位置/干扰物/背景/未见物品/人为干扰）× 2
单次最长 180s；超时失败
排名：总平均成功率 > 总平均步骤分 > 提交日期
仅通才单模型赛道；不计分单任务调试通道只用于自测
```

**算术**：320 trials；在 p≈0.3 时总体 SE≈**2.56pp**；单任务 10 trials SE≈**14.5pp**；单轴 64 trials SE≈**5.73pp**。独立两比例 80% 功效约需 10pp 差异；配对设计约需 7pp。所以官方 320-episode 跑是“终局确认”，不是“日常迭代”；日常用 KRB 离线配对和小规模调试槽。

### 1.2 提交接口 v2：动作/观测/时序

来自 `unibot_submission` README 与本地 stub（[S6][S7]）：

| 项 | 内容 |
|---|---|
| 观测 | 4×RGB 480×640；双臂 7 维关节；双臂 EE pose（base 系，xyz+rpy）；左右夹爪；`lower_body`[15]；`language` 单字符串 |
| 缺失 | 力矩/力/触觉/电流/深度/麦克风 |
| 动作空间 | `control_space="joint"` 或 `"ee"`，互斥 |
| joint 动作 | `action.left_arm`[7]、`action.right_arm`[7] |
| ee 动作 | `action.left_ee_pose_gripper_base`[6]、right[6] |
| 共享动作 | `action.left_gripper`[1]、`action.right_gripper`[1]、`action.pivot`[7] |
| chunk | `action_chunk_size` 固定；index 0 先执行，其余顺序执行，直到下一次调用；无 mid-chunk 异步 |
| 观测选择 | `obs_delta_indices` 决定传哪些键 + 每键堆叠几帧；`image_resize` 决定分辨率 |
| 部署 | N 个连续端口（官方指定），每端口独立进程/状态；token 双处校验；延迟被记录 |

**关键含义**：

- 我们完全控制观测裁剪、图像缩放、时序堆叠、chunk 大小；KRA/DAC 的输入输出都在 API 允许范围内。
- chunk 整段执行意味着“反应性”只能通过更小的 T、terminal-safe chunk、边界 C1、接触原语来换。
- joint 模式让我们能直接控制 7-DOF 冗余，也让 KRM 能直接看到“命令关节 vs 观测关节”的残差；EE 模式则把这两件事交给低层 IK，KRA/KRM 失效。

### 1.3 `action.pivot` 不是腰（本轮接口纠偏）

官方数据集 `action.pivot` 的字段名是 `[vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]`（[S8]）。我们直接对比两个分片（[S8][S9]）：

| 检查 | 结果 |
|---|---|
| `pivot[0:3]` vs `action.base_command[0:3]` | 逐帧完全相等（max diff = 0） |
| `pivot[6]` vs `action.base_command[3]`（height） | 逐帧完全相等（max diff = 0） |
| `pivot_3` / `pivot_4` / `pivot_5` | HangCup 与 PlugCharger 全是常量 **0 / 0.15 / 0** |
| `pivot_3..5` vs `waist_state_joint` | 常量，无变化；腰状态在动，二者不一致 |
| `action.waist_action_joint` | 数据集有 [3]；**提交 API 动作目录没有这个键** |

**结论**：

- `action.pivot` 是 **base（底盘）+ 高度** 的低层命令，不是 3-DOF 腰。`pivot_3..5` 的语义官方未公开；两个分片里它们是固定值（可能是步态/站姿参数）；不要把它当腰。
- API 只暴露腰的观测（`lower_body` 后三维 / `waist_state_joint` 在数据里），不暴露腰的动作。**腰可观测、不可命令。**
- KRA 必须在 FK 中把腰当作**已观测的准静态基座变换**；不能把腰当自由变量。任何“用腰提升余量”的结果只能作为离线可达性上界，不能进主路径。

### 1.5 G1 29-DOF 与 URDF

- G1 EDU 29-DOF：**每臂 7 DOF、腰 3 DOF、每腿 6 DOF**（[S11][S12]）。
- 挑战数据用 7-DOF 臂 + 3-DOF 腰；URDF `g1_29dof_rev_1_0.urdf` 给出完整关节限位（[S13]）。
- 数据集 `lower_body`[15] = 12 腿 + 3 腰；`waist_state_joint`[3]；`action.lower_body`[15]；`action.waist_action_joint`[3]。
- 提交 API 只给臂 + 夹爪 + pivot；没有 lower_body/waist 动作。**29-DOF 机械体，但策略可写的是 14 个臂关节 + 2 个夹爪 + 7 个 base/pivot。**

### 1.6 WLA-1.0-Base：6B、30-step、相对 EE、3 相机

- 模型：**6B** 参数、Apache-2.0、约 **2,500h** 真机数据、**64** 任务；支持 LoRA/action-expert 微调（[S14][S15]）。
- 默认数据配置：`target_fps: 30`、`chunk_size: 30`（约 1s）、`image_size: [336,448]`；动作是**相对当前 EE 的 SE(3)**；训练用 3 路图（head left + 左右腕），不是 4 路（[S15]）。
- 统一动作 54 维：左右 EE（相对）、夹爪、腰 3、torso 3、base 4、高度 1、腿 12；挑战 API 只接受臂 + 夹爪 + pivot。**模型能输出腰/腿，但 API 会忽略/拒绝；adapter 必须 mask，并在挑战数据上微调 action expert。**
- 这给出明确的工程链：**WLA 相对 EE chunk → 绝对 EE → KRA IK → 绝对关节 chunk**；EE 模式只需相对→绝对，但 KRA/KRM 失效。

### 1.7 实时控制文献

- **RTC**（Real-Time Chunking，arXiv 2506.07339，2025/NeurIPS 2025）：执行当前 chunk 时生成下一个，冻结保证执行的前缀，inpaint 其余；适用于 diffusion/flow VLA，无需重训（[S16]）。
- **REMAC**（Real-Time Robot Execution with Masked Action Chunking，arXiv 2601.20130，2026）：用 masked action chunking 处理推理延迟；前缀条件化/掩码（[S17]）。
- **Action Chunk Scheduling**（arXiv 2608.00337，2026）：多机器人服务时 chunk 太长会失去反应性、太短会饥饿；调度要按机器人时间而不是请求时间（[S18]）。
- **本 API 的限制**：evaluator 同步调用，执行完整个 chunk 才再次调用；不能真异步。**能借鉴的是边界连续性/延迟感知 horizon，而不是执行中推理。**

## 2. 运动学审计（本轮核心实验）

### 2.1 方法

**数据**：HangCup `file-001`（324 eps / 63,999 帧）与 PlugCharger `file-003`（169 eps / 70,910 帧）。

**URDF**：官方 `g1_29dof_rev_1_0.urdf`（[S13]）。

**FK**：从 base 到 `left_rubber_hand`/`right_rubber_hand` 逐关节变换；腰 3 关节来自 `observation.state.waist_state_joint`；工具偏移 `TOOL=[0.0665,0,0]` 加在 palm 之后，得到 gripper base 位姿。

**对齐**：与 `observation.state.left_ee_pose_gripper_base` 的 xyz 和旋转矩阵比较；残差用 `std`（因为存在固定工具偏移/安装偏差）。

**关节顺序搜索**：对腕部三轴的所有排列/符号做 FK，选残差最小者；结果唯一指向 URDF 顺序。

**限位余量**：`m_j = min(q_j - q_min_j, q_max_j - q_j) / (q_max_j - q_min_j)`；统计 `m_j < 0.10` / `< 0.05` 的帧比例。

**swivel**：在肩-腕连线的局部柱坐标里，计算肘部绕 shoulder-wrist 轴的角度；统计每 episode 的 span 和 swivel 圆半径。

**IK**：阻尼最小二乘 + 限位裁剪；arm-only 7 变量，6D 目标；40 个随机种子（1 个 demo 解 + 39 个扰动）。成功判据：位置 <2mm、姿态 <0.02 rad。腰上界实验用 10 变量（7 臂 + 3 腰），同样 40 种子；**仅离线诊断**。

### 2.2 FK 标定：列名陷阱与工具偏移

| 检查 | 结果 |
|---|---|
| 躯干 FK vs `observation.state.state_torso` | 完全吻合（验证 URDF/腰顺序） |
| 手臂 FK vs EE（URDF 顺序） | 位置残差 std **1.14mm（HangCup）/0.98mm（PlugCharger）**；姿态残差 0 |
| 按 parquet 字段名直观映射 | 位置误差约 **10cm** |
| 工具偏移 | gripper base 相对 palm **6.65cm**（沿 palm x）；加后残差 std ~1mm |
| 残差均值（HangCup） | `[0.19, 0.68, 0] mm` |
| 残差均值（PlugCharger） | `[-2.18, 1.83, 0] mm` |

**列名陷阱**：parquet `names` 写的是 `shoulder_pitch, shoulder_roll, shoulder_yaw, elbow, wrist_yaw, wrist_roll, wrist_pitch`，但数值实际按 URDF 的 `wrist_roll → wrist_pitch → wrist_yaw` 排列。也就是说：

```text
字段名索引:  4=wrist_yaw, 5=wrist_roll, 6=wrist_pitch
数值索引:    4=wrist_roll, 5=wrist_pitch, 6=wrist_yaw
```

任何按名字直接喂关节的模型都会学到错标签。**这也是一个可复现的“数据陷阱”**：如果头部模型用 joint-space 训练，可能有一部分误差来自这里。

**API 关节顺序**：API 的 `action.left_arm`[7] 没有给名字；数据集数值顺序是否等于 API 顺序，官方没写。**必须在调试槽做单关节标定**（小幅运动 + 观测响应），否则 joint 模式可能把 `wrist_yaw` 发到 `wrist_roll`。标定前，EE 模式更安全；标定后，joint 模式才可用。

### 2.3 限位审计：PlugCharger 贴着腕限位

`wrist_yaw` 范围 ±1.614 rad（总 3.228 rad）；**5% = 0.161 rad = 9.2°**，10% = 18.5°。

| 任务（分片） | 帧 / episodes | 左腕 yaw <10% / <5% | 右腕 yaw <10% / <5% | 任一关节 <10%（L/R） | 肘屈曲 p95 | per-episode swivel span p50 | swivel 半径 p5 |
|---|---:|---:|---:|---:|---:|---:|---:|
| HangCup file-001 | 63,999 / 324 | 0.9% / 0.1% | 3.0% / 0.1% | 2.8% / 7.3% | 88.3° | 29.2° | 9.17cm |
| PlugCharger file-003 | 70,910 / 169 | **74.4% / 49.1%** | **43.9% / 8.3%** | **74.9% / 44.2%** | **163.5°** | 46.0° | **1.95cm** |

补充：

- PlugCharger 左腕 `wrist_yaw` 的 p5/p50/p95 约为 `-1.611 / -1.448 / -1.030 rad`；下限 `-1.614 rad`。中位距离下限只有 **9.5°**。
- 右腕 `wrist_yaw` 的 p5/p50/p95 约为 `0.463 / 1.260 / 1.494 rad`；上限 `1.614 rad`；8.3% 的帧在 5% 以内。
- HangCup 的肘屈曲 p5/p50/p95 约 `63.0 / 75.0 / 88.3°`；PlugCharger 为 `85.4 / 125.3 / 163.5°`。
- 这是“任务 regime”差异，不是噪声：PlugCharger 需要接近全伸展去够插排；HangCup 是弯肘挂杯。

### 2.4 swivel/肘部：两个任务在相反的运动学 regime

| 指标 | HangCup | PlugCharger | 含义 |
|---|---:|---:|---|
| 肘屈曲 p5/p50/p95 | 63.0 / 75.0 / 88.3° | 85.4 / 125.3 / 163.5° | Plug 更接近伸直 |
| swivel 半径 p5/p50/p95 | 9.17 / 9.79 / 10.04 cm | 1.95 / 6.16 / 9.41 cm | Plug 有更小的可操作度 |
| 每 episode swivel span p5/p50/p95 | 12.7 / 29.2 / 59.2° | 15.7 / 46.0 / 69.3° | Plug 需要更大的肘部重构 |
| 全数据 swivel span | 80.9° | 170.5° | Plug 的构型变化更大 |

**解释**：PlugCharger 的插入点较远/较低，手臂接近全伸展；此时腕部要同时满足位置和姿态，7-DOF 冗余被“拉直”，腕 yaw 很容易顶到限位。HangCup 的挂杯点在近处，肘部弯曲，余量更大。**KRA 不能用一个全局“回中”目标**；必须按任务/相位选择 regime：插入任务要“留一点弯肘/抬高可操作度”，挂杯任务要“保持示范构型”。

### 2.5 IK 零空间：臂的余量有限，腰上界不可部署

12 个 `wrist_yaw` 饱和帧（demo margin 0.1–3.0%），40 随机种子：

| 指标 | arm-only（7 变量） | +3-DOF 腰（10 变量，离线上界） |
|---|---|---|
| IK 成功 | 多数 40/40；一帧 **12/40**；一帧 37/40 | **12/12 帧 40/40** |
| `wrist_yaw` 最大余量 | **2.1–10.0%**（中位 0–3.7%） | **5.5–18.0%**（中位 0.1–2.7%） |
| 关节重构 p50 | 0.08–0.54 rad（臂） | 臂 0.41–0.61 rad；腰 0.17–0.27 rad |
| 结论 | 能改善但有限；有些帧确实难 | 腰能显著改善，但**API 不可命令**，只能当上界 |

```text
frame 32622: demo wy_margin=0.019, success=37/40,  max/med margin=0.100/0.037

frame 49749: demo wy_margin=0.001, success=40/40,  max/med margin=0.086/0.000
```

**现实预期**：arm-only KRA 不能把 0 余量变成很大，但能把“贴着限位”变成“有 2–10% 余量”，并把关节重构控制在 ~0.1–0.5 rad。对于 OOD 位置/未见物体，这几度到十几度的余量可能就是从失败到成功。**不要承诺腰的收益。**

### 2.6 工具偏移放大姿态误差

gripper base 相对 palm 的 6.65cm 偏移意味着绕垂直于工具轴的姿态误差会放大成 TCP 误差：

| 姿态误差 | TCP 误差（6.65cm 杠杆） |
|---:|---:|
| 1° | 1.16mm |
| 2° | 2.32mm |
| 5° | 5.81mm |
| 10° | 11.64mm |

插入/堆叠容差常常是 1–5mm；**腕部限位/低层 IK 的“保位置、丢姿态”会直接放大成 TCP 误差**。KRA 的零空间目标必须优先保姿态和腕部余量，而不是只保位置。

### 2.7 为什么这能解释“榜首不到 30%”

- 32 个任务里，大量终局是插入/堆叠/闭合（T10/T26/T05/T12/T27/T20/T25/T19/T23/T31…）；这些任务对末端姿态和限位余量最敏感。
- 演示在 PlugCharger 上已经把腕 yaw 用到 5% 以内；行为克隆会继承这个“边界构型”，OOD 位置/未见物体一扰动，腕部没有余量，低层 IK 只能牺牲姿态或位置。
- 6.65cm 工具偏移把姿态误差放大到毫米级；插入容差是毫米级。**“看起来到了，但插不进去”** 的典型机制。
- chunk 整段执行让接触段反馈频率降到 1–4Hz；边界 jerk/过冲进一步破坏插入。**运动学 + 时序是同一个“最后一公里”问题的两面。**

### 2.8 局限

- 只审计了两个分片，不是 32 任务全量；结论是“这两个任务 regime 的证据”，不是全任务统计。
- IK 用数值阻尼最小二乘，不是工业级 QP；成功率和余量是下界/近似。
- 未模拟低层控制器的插值/限幅/安全层；真机行为需调试槽验证。
- 未验证 API 关节顺序；joint 模式的 KRA 必须先标定。
- 未验证 evaluator 是否对 joint 目标做限幅/拒绝；KRA 输出必须在 URDF 限位内。
- `pivot_3..5` 的语义官方未公开；我们只证明它不等于腰，不证明它具体是什么。

## 3. KINE-EXEC 架构

### 3.1 总览

```text
┌──────────────────────── Offline（KRB）────────────────────────┐
│ 官方 33k（HangCup/PlugCharger 分片起步）                       │
│  ├─ FK 标定：URDF + 关节顺序 + 工具偏移                        │

└───────────────────────────────────────────────────────────────┘
                              │
┌──────────────────────── Inference（单一 checkpoint）──────────┐
│ language → SSG 相位/步骤 → PGL/OPT 目标位姿                    │
│ obs(4 RGB + proprio) → WLA/GPR-VLA → 相对 EE chunk              │
│                              │                                 │
│                              ▼                                 │
│ KRA：绝对 EE → 7-DOF 关节目标（限位/奇异/自碰撞/双臂/示范先验）│
│                              │                                 │
│                              ▼                                 │
│ DAC：时间参数化 + C1 + terminal-safe + 接触原语 + 延迟补偿      │
│                              │                                 │
│                              ▼                                 │

└───────────────────────────────────────────────────────────────┘
```

### 3.2 数据流

1. `obs`：4 路 RGB、双臂关节、EE pose、夹爪、lower_body、language。
2. SSG：把 language 映射到任务/步骤；输出相位 `phase`（approach/contact/close/retreat）和期望步骤。
3. PGL/OPT：输出目标 EE pose（base 系）或目标物体相对位姿；这是“做什么/放哪里”。
4. WLA/GPR：输出相对 EE chunk（T×6 或 T×7 含夹爪）；可选输出夹爪。
5. KRA：把相对 EE 转绝对 EE（用当前 EE），再 IK 成关节；输出 T×7 双臂关节 + 夹爪。
6. DAC：对关节 chunk 做时间参数化、C1、terminal-safe、接触原语；输出最终 joint chunk。
7. evaluator 执行 chunk；下一次调用时，KRM 用 `q_obs`/`q_cmd`/gripper/phase 判断是否恢复。
8. 恢复：在下一个 chunk 里执行慢退/重试/螺旋/重抓/换手；KRA 可换构型。

### 3.3 组件接口

```python

    waist=waist_obs,          # 3, observed; used in FK only

# DAC

# KRM
```

### 3.4 为什么 joint 模式 + KRA，而不是纯 EE

| 维度 | EE 模式 | joint 模式 + KRA |
|---|---|---|
| 7-DOF 冗余 | 低层 IK 隐式处理，可能贴限位/奇异 | 显式控制，零空间留余量 |
| 限位余量 | 不可见/不可控 | 可观、可优化 |
| 关节跟踪残差 | 低层 IK 吃掉，KRM 难判断 | 直接可见，KRM 可用 |
| 关节顺序风险 | 无 | 有；必须标定 |
| 低层控制器冲突 | 小 | 中；需测试 |
| 任务几何 | 直接 | 信任域内保持 |

**结论**：先用 EE 模式做基线；在调试槽完成关节顺序/低层跟踪标定后，切 joint + KRA。KRA 不是“替代低层 IK”，而是“在低层 IK 之上加约束和余量”。

### 3.5 单模型合规

- 唯一学习模型：WLA/GPR checkpoint（可 LoRA/action expert 微调）。
- KRA：URDF + 数值 IK/QP，确定性。
- DAC：时间参数化/插值/状态机，确定性。
- KRM：统计阈值/规则，确定性；不训练第二个模型。
- PGL/OPT/SSG：确定性代码 + 数据表；不是模型。
- 模型卡披露所有组件；不碰外部数据/仿真 RL/每任务 LoRA。

## 4. KRA：运动学冗余适配器

### 4.1 问题定义

给定：

- 目标 EE pose `T* ∈ SE(3)`（base 系）；
- 当前关节 `q_obs ∈ R^7`（每臂）；
- 观测腰 `w ∈ R^3`（准静态基座变换）；
- 关节限位 `[q_min, q_max]`；
- 可选：同任务/同相位的示范关节先验 `q_demo`、双臂相对位姿约束、自碰撞模型。

求：`q* ∈ R^7`，使 `FK(q*, w)` 接近 `T*`，同时在零空间里最大化限位余量/可操作度/平滑性，并保持接近示范。

### 4.2 约束优化

```text
min_{dq}  ||J(q) dq - e||^2_W
        + λ1 ||dq||^2
        + λ2 ||(q + dq) - q_demo||^2_P
        + λ3 ||(q + dq) - q_center||^2
        + λ4 * barrier(q + dq)

s.t.      q_min + m <= q + dq <= q_max - m
          |dq| <= dq_max
          |dq - dq_prev| <= ddq_max * dt
          sigma_min(J(q)) >= sigma_eps          # soft
          d_self(q) >= d_safe                   # optional
          ||p_L - p_R - d_rel|| <= eps_bimanual # optional
```

其中：

- `e = log(T* T(q)^{-1}) ∈ R^6`（位置 + 旋转向量）。
- `W = diag(w_p, w_p, w_p, w_r, w_r, w_r)`；插入任务可提高 `w_r`。
- `m`：限位余量，建议 3–5% 行程；对 `wrist_yaw` 可提高到 8–10%。
- `barrier`：对接近限位的关节加 `-log(q - q_min - m) - log(q_max - m - q)` 或软惩罚。
- `q_center`：关节范围中点；`q_demo`：同相位示范中位数。
- `P`：相位相关权重；插入任务对肘/腕 yaw 权重高，挂杯任务对肩/肘权重高。

**求解**：小规模（7 变量）用阻尼最小二乘 + 零空间投影即可；需要硬约束时用 OSQP/qpOASES。30–100Hz 的 rank-6 更新在 CPU 上很便宜；不要每帧从零解，热启动 `q_prev`。

### 4.3 零空间目标（关键）

单纯“回中”会破坏示范构型；KRA 的零空间目标要分层：

1. **限位余量**（最高）：对 `m_j < 10%` 的关节加排斥；优先 `wrist_yaw`、`wrist_pitch`、`elbow`。
2. **可操作度**（高）：`sigma_min(J)` 或 `sqrt(det(JJ^T))`；PlugCharger 的 swivel 半径 p5 只有 1.95cm，必须避免继续靠近奇异。
3. **示范 regime**（中）：用同任务/同相位的 `q_demo` 分布；不是复制轨迹，而是“肘/腕在哪个 regime”。HangCup（弯肘 75°）与 PlugCharger（伸展 125–163°）不能混。
4. **双臂相对位姿**（中，双臂任务）：保持两手相对位姿/角色；软约束，避免硬约束导致不可行。
5. **平滑**（低）：`||dq||^2`、`||q - q_prev||^2`；避免 chunk 内抖动。

**regime 条件化**：SSG 给出任务/步骤；KRA 查表得到该相位的 `q_demo`、权重、限位余量目标。表由 KRB 离线统计生成，不是学习模型。

### 4.4 信任域

KRA 不应偏离低层 IK/示范太远：

```text
||q - q_ref|| <= r_trust     # 例如 0.3–0.5 rad
```

如果为了余量需要更大重构，标记 `confidence=low`，由 KRM/策略决定是否接受；或者只在 `phase=approach` 做重构，`phase=contact` 保持稳定。**接触段不要大改构型**，否则会破坏已对齐的接触。

### 4.5 伪代码

```python
def kra_solve(T_target, q_seed, waist, phase, q_demo, q_prev, dt):
    q = q_seed.copy()
    prior = prior_table[phase]           # q_demo, weights, margin target
    for it in range(N_ITERS):
        T = fk_arm(q, waist)
        e = se3_log(T_target @ inv(T))   # 6
        J = jacobian_arm(q, waist)       # 6x7
        # null-space projector
        J_pinv = J.T @ inv(J @ J.T + lam * I)
        dq_task = J_pinv @ e
        N = I - J_pinv @ J
        # null-space desire: limit margin + manipulability + demo
        g_lim = grad_limit_margin(q, q_min, q_max, prior.margin)
        g_man = grad_manipulability(J)
        g_demo = prior.q_demo - q
        dq_null = k_lim*g_lim + k_man*g_man + k_demo*g_demo
        dq = dq_task + N @ dq_null
        # trust region + limits + velocity
        dq = clip(dq, -dq_max, dq_max)
        q_new = clip_with_margin(q + dq, q_min, q_max, prior.margin)
        q_new = trust_region(q_new, q_seed, r_trust)
        if norm(e) < eps and norm(q_new - q) < eps:
            break
        q = q_new
    return q, confidence(q, e, q_seed)
```

### 4.6 标定协议（joint 模式前必须做）

1. **关节顺序**：在调试槽让单关节小幅运动（例如 `wrist_yaw` ±0.1 rad），观察 EE/关节响应；确认 API 索引与数据集数值顺序一致。若不一致，建立映射表。
2. **工具偏移/末端帧**：用已知 EE pose + FK 对齐，确认 6.65cm 偏移和 gripper base 定义；不同夹爪/安装可能不同。
3. **低层跟踪**：发阶跃/正弦关节目标，测跟踪延迟、超调、限幅；确认 DAC 的时间参数化不会被低层覆盖。
4. **安全限位**：确认 evaluator 是否拒绝/裁剪超限目标；KRA 必须在 URDF 限位内留 margin。
5. **pivot 默认值**：确认输出 0 是否安全；若 evaluator 期望数据集常量（前三维 0、后三维 0/0.15/0、height 用默认），用常量；不要依赖 pivot 控制腰。

### 4.7 双臂约束

- T26/T05：一手固定网口/插排，另一手插/拔；保持相对位姿 `d_rel` 和角色分配。
- T18/T28：一手开袋/盒，另一手放；保持袋口/盒盖的相对位姿。
- 用软约束：`||p_L - p_R - d_rel|| <= eps`，权重低于 EE 目标；避免硬约束导致 IK 不可行。
- 角色分配由 SSG 相位决定；不要在接触段换手，除非 KRM 触发。

### 4.8 KRA 指标

- IK 回放成功率（TCP <2mm，姿态 <1°）。
- 限位违规率（<1% 帧）。
- 饱和帧 margin 提升 ≥5% 的占比（目标 ≥50%）。
- 关节重构 p50/p95（目标 p95 <0.5 rad）。
- IK 时间 p99（目标 <10ms/臂，30Hz 下绰绰有余）。
- 与 demo 的关节距离（信任域内）。

## 5. DAC：延迟感知 chunk 编译器

### 5.1 时序模型

API 是同步 chunk：evaluator 调 `get_action`，执行 T 步，再调下一次。设推理+网络延迟 `L` 秒，chunk 时长 `T/30` 秒：

```text
平均观测年龄  age ≈ L + T/(2*30)
执行占空比    duty ≈ T/(T + 30L)
```

`age` 是“动作执行时，它基于多旧的观测”；`duty` 是机器人“有动作可执行”的时间比例。接触任务要 `age` 小；自由空间可以 `duty` 高。

### 5.2 延迟表

| L | T=2 | T=4 | T=8 | T=16 | T=30 |
|---:|---:|---:|---:|---:|---:|
| 100ms | 133ms / 40% | 167ms / 57% | 233ms / 73% | 367ms / 84% | 600ms / 91% |
| 200ms | 233ms / 25% | 267ms / 40% | 333ms / 57% | 467ms / 73% | 700ms / 83% |
| 300ms | 333ms / 18% | 367ms / 31% | 433ms / 47% | 567ms / 64% | 800ms / 77% |

**选择**：

- 接触任务目标 `age <200ms`：L=100ms → T=2–4；L=200ms → T=2–4 仍勉强；L=300ms → 必须加速模型/接受慢接触。
- 自由空间/长程移动：T=8–16 可接受；T=30 只在 L 很低且任务很慢时用。
- 本 API 的 `action_chunk_size` 在 handshake 固定；建议全局 **T=4–8**，接触段用 terminal-safe/有效 horizon 缩短，而不是动态改 T。

### 5.3 时间参数化

把模型输出的离散关节/EE 路点拟合成连续轨迹：

- **min-jerk**：`s(t)=10t^3-15t^4+6t^5`，适合点到点；接触段用梯形速度/低加速度。
- **限幅**：`|v| <= v_max`、`|a| <= a_max`、`|jerk| <= j_max`；v_max/a_max 从演示统计 + 低层能力估计。
- **时间缩放**：如果模型输出太快，拉伸时间；如果太慢，压缩到限幅内。不要改变几何路径，只改时间。
- **关节空间 vs EE 空间**：KRA 已在关节空间；DAC 直接在关节空间做限幅/平滑，避免 EE 空间再 IK 一次。

### 5.4 C1 拼接

在 chunk 边界：

```text
q_new(0) = q_obs
dq_new(0) = (q_obs - q_prev_obs) / dt   # 或用低层估计
```

如果模型输出绝对目标，用“当前状态 + 模型增量”而不是“模型绝对目标”；如果必须用绝对，做位置/速度混合：

```text
q_exec = (1-α) * q_model + α * (q_obs + dq_obs * t)
```

`α` 在边界 1–2 步内从 1 降到 0，避免跳变；但不要过度平滑到任务滞后。目标是 C1（位置/速度连续），不是 C2。

### 5.5 Terminal-safe chunk

因为 evaluator 执行整个 chunk，且下一次调用可能晚到，chunk 末尾必须是安全动作：

- 自由空间：最后 1 步保持/轻微减速。
- 接触段：最后 1–2 步“保持位置 + 夹爪保持”，不要继续下压/快速移动。
- 抓取段：最后 1 步夹爪保持，不要在半开半合时结束。
- 如果 `phase=retreat`：最后一步可以是回撤到位，但速度受限。

这牺牲一点任务进度，换取“晚到不冲过头”。在 180s 预算内，值得。

### 5.6 接触原语（插入类）

对 T10/T26/T05/T12/T32：

1. **视觉粗对齐**：PGL/OPT 给目标；KRA 到预插入 pose，留 1–2cm 轴向间隙。
2. **慢速轴向接近**：DAC 降低速度，terminal-safe；KRM 监控残差。
3. **螺旋/抖动搜索**：如果残差显示接触但未插入，做小幅螺旋（半径 1–3mm，频率 1–2Hz）或正交抖动；每次 0.5–1s。
4. **轴向慢推**：在搜索的同时保持轴向力（位置模式下用小幅位移），KRM 看残差是否下降/EE 是否前进。
5. **到位判定**：EE 前进到目标深度 + 残差回落 + 夹爪/视觉确认；然后释放/回撤。
6. **失败**：回退 1–3cm，重试；最多 2 次；仍失败则标记，进入下一步/恢复。

这是经典 peg-in-hole 的无传感器变体（[S20]），用关节残差替代力觉。

### 5.7 可选加速（工程）

如果 model server 可改：

- **VLM latent 缓存**：视觉/语言变化慢时，复用 VLM 特征，只跑 action expert；需要验证特征是否包含当前状态。
- **Action expert 复用**：同一观测下多次采样/短 chunk；不要把它当新模型。
- **蒸馏/小 action expert**：如果 6B 太慢；仍是一个 checkpoint 的 action expert，需确认单模型规则。
- **批处理/N 端口**：官方多端口；每端口独立，不要共享可变状态。

这些是“如果时间允许”的优化；主路径先测 L，再决定。

### 5.8 伪代码

```python
def dac_compile(q_ref, gripper, state, phase, L, dt=1/30):
    # q_ref: T x 14 absolute joint targets from KRA
    # 1. time parameterization
    q_smooth = min_jerk_resample(q_ref, dt, v_max, a_max, j_max)
    # 2. terminal-safe
    if phase in ("contact", "close", "grasp"):
        q_smooth[-1] = q_smooth[-2]       # hold last
        gripper[-1] = gripper[-2]
    # 3. C1 stitch at boundary
    q_smooth = c1_stitch(q_smooth, state.q, state.dq, dt, blend_steps=2)
    # 4. contact primitive
    if phase == "insert":
        q_smooth = spiral_search(q_smooth, radius=0.002, turns=1.5, axis="z")
    # 5. limits
    q_smooth = clip_with_margin(q_smooth, q_min, q_max, margin=0.03)
    return q_smooth, gripper
```

### 5.9 DAC 指标

- 边界 jerk 降低 ≥50%（相对无 C1/terminal-safe）。
- 延迟注入下跟踪 RMSE 不劣于 baseline 10%。
- 过冲/超调降低；接触段最大穿透/力代理降低。
- 有效占空比/任务完成时间在 180s 内。
- 无“因为 terminal-safe 导致任务没做完”的回归。

## 6. KRM：运动学残差监控与恢复

### 6.1 可观测信号

joint 模式：

- `q_cmd`（我们发的关节目标）、`q_obs`（下一次观测的关节）。
- `r_q = q_obs - q_cmd`；`r_task = J(q_obs) r_q`（任务空间投影）。
- `r_ee = FK(q_obs) - EE_cmd`（如果有 EE 命令）。
- 限位余量 `m(q_obs)`；可操作度 `sigma_min(J)`；`|dq|`、`|ddq|`。
- 夹爪开度/命令差；SSG 相位；视觉变化（可选）。

EE 模式：

- `r_ee` 仍可算，但低层 IK 会吃掉关节残差；KRM 信息少。**这是 joint 模式的另一个理由。**

### 6.2 特征

| 特征 | 含义 | 用途 |
|---|---|---|
| `||r_q||` / `||r_task||` | 跟踪残差 | 接触/卡住/限位 |
| `r_q` 方向 vs 命令方向 | 残差是否沿运动方向 | 接触/阻挡 |
| `m(q_obs)` | 限位余量 | 限位/构型 |
| `sigma_min(J)` | 可操作度 | 奇异/难构型 |
| 夹爪差 | 开度 vs 命令 | 滑脱/抓空 |
| 相位 one-hot | approach/contact/close/retreat | 条件化阈值 |
| 视觉目标位移 | 物体是否被移动 | 撤销/干扰 |
| 残差斜率/方差 | 持续 vs 瞬时 | 接触 vs 噪声 |

### 6.3 阈值

- 用成功演示的残差分布，按任务/相位分桶；取 p95/p99 或 conformal 分位数。
- 轻物体（HangCup）残差弱：不要用单一全局阈值；结合夹爪/视觉/相位。
- 前轮数据：PlugCharger 插入段 vs 自由段 AUROC 0.866；HangCup 轻杯只有 0.722。**KRM 必须分任务/分相位，否则会被平均掉。**
- 误报目标 <10%；如果达不到，只做诊断，不触发恢复。

### 6.4 状态机

```text
IDLE → APPROACH → CONTACT → INSERT/CLOSE → VERIFY → DONE
         │           │          │             │
         └─ limit ───┴─ stuck ──┴─ slip ──────┴─ undo
```

- `APPROACH`：残差正常；如果 limit → KRA 换构型/回退。
- `CONTACT`：残差升高是预期的；如果持续升高且无前进 → stuck；如果突然回落 + 前进 → inserted。
- `CLOSE`：夹爪差/残差；如果滑脱 → 重抓。
- `VERIFY`：SSG 谓词/视觉；如果失败 → 重试/恢复。
- `undo`：物体位置/谓词从 1→0 → 回退到上一步。

### 6.5 恢复原语

| 事件 | 恢复 |
|---|---|
| 限位 | 回退 1–2cm；KRA 换构型（零空间）；重试 |
| 卡住 | 回退 1–3cm；螺旋/抖动；轴向慢推 |
| 滑脱 | 张开夹爪；重抓；检查抓取点 |
| 抓空 | 重新接近；调整高度/姿态 |
| 撤销/干扰 | 回退到安全 pose；重做上一步 |
| 超时 | 放弃当前尝试；进入下一步/结束 |

每个 episode 限制恢复次数（例如 2–3 次），避免 180s 超时；长程任务（T16/T17/T31）更严格。

### 6.6 伪代码

```python
def krm_check(q_obs, q_cmd, grip_obs, grip_cmd, phase, hist):
    r = q_obs - q_cmd
    J = jacobian_arm(q_obs, waist_obs)
    r_task = J @ r
    margin = min_limit_margin(q_obs)
    manip = sigma_min(J)
    feat = {
        "r_norm": norm(r),
        "r_task_norm": norm(r_task),
        "margin": margin,
        "manip": manip,
        "grip_diff": grip_obs - grip_cmd,
        "phase": phase,
    }
    if phase in CONTACT and feat["r_task_norm"] > th_contact[phase]:
        if hist.slope(r_task) > 0 and hist.speed(q_obs) < eps:
            return "stuck"
        return "contact"
    if margin < 0.05 and hist.dot(r, limit_dir(q_obs)) > 0:
        return "limit"
    if abs(feat["grip_diff"]) > th_slip:
        return "slip"
    return "ok"

def recover(event, phase):
    if event == "limit":  return ["retreat", "kra_reconfigure", "retry"]
    if event == "stuck":  return ["retreat", "spiral", "retry"]
    if event == "slip":   return ["open", "regrasp"]
    if event == "undo":   return ["safe_pose", "redo_step"]
    return []
```

### 6.7 KRM 指标

- 接触/非接触 AUROC ≥0.8；TPR@5%FPR。
- 限位/卡住/滑脱的分类混淆矩阵。
- 误报率 <10%；恢复成功率 ≥50%（离线模拟/调试槽）。
- 恢复带来的任务成功率增益 vs 时间成本。
- 在轻物体任务上不退化（HangCup 类）。

**如果时间不够**：优先 KRA + DAC；KRM 只做诊断；PGL/OPT/SSG 保留但不扩；ICR/L2L/TCLB 全砍。

## 11. 风险、合规与开关

| 风险 | 概率 | 影响 | 缓解 | 停止条件 |
|---|---|---|---|---|
| API 关节顺序与数据集不一致 | 中 | 高 | 调试槽单关节标定；标定前 EE 模式 | 标定失败 → 不上 joint |
| `pivot` 被 evaluator 解释成腰/其他 | 低 | 高 | 不依赖 pivot；默认 0/数据集常量；调试槽验证 | 发现影响 → 重评 |
| 低层控制器覆盖 DAC 时间参数化 | 中 | 中 | 阶跃/正弦跟踪测试；只做软整形 | 无改善 → 关闭整形 |
| KRA 偏离示范导致任务几何变差 | 中 | 高 | 信任域 + 零空间 + KRB 回放 | 回放成功率降 → 收紧 |
| IK 延迟/CPU | 低 | 中 | 小 QP/热启动；30–100Hz | p99 >10ms → 降频 |
| KRM 误报/恢复耗时 | 中 | 中 | 分任务/相位阈值；恢复限次；180s 守卫 | 误报 >15% → 只诊断 |
| 轻物体残差弱 | 高 | 中 | 融合夹爪/视觉/相位；不单独依赖残差 | HangCup 退化 → 关闭该任务恢复 |
| 单模型审计 | 低 | 高 | KRA/DAC/KRM 确定性；唯一 checkpoint；模型卡 | 审计不过 → 去学习成分 |
| 统计噪声 | 高 | 中 | 320 trials + 配对 + bootstrap；不追 1–2pp | CI 跨 0 → 不上线 |
| 外部数据/合作违规 | 低 | 高 | 本轮不用外部数据；KRB 只用官方 | 规则禁止 → 砍 L2L |
| 调试槽不可用 | 中 | 高 | KRB 兜底；保守提交 | 无法验证 → 不上 joint |

### 合规开关

```yaml
policy:
  learning_model: wla_gpr_single_checkpoint
  kine_layer: deterministic        # KRA/DAC/KRM
  external_data: false
  simulation_rl: false
  per_task_lora: false
  tactile_force_input: false
  joint_mode: after_calibration    # EE before calibration
  pivot: default_or_dataset_const  # not used for waist
  debug_loop_budget_per_release: 1
  model_card: true
```

**模型卡必须写清**：

- 唯一学习模型：WLA/GPR checkpoint（参数、训练数据、LoRA/action expert）。
- KRA：URDF 版本、关节顺序、工具偏移、限位 margin、QP 参数。
- DAC：chunk size、延迟模型、时间参数化、terminal-safe、接触原语。
- KRM：特征、阈值来源（官方演示分位数）、恢复原语、触发次数上限。
- 数据：官方 33k；无外部数据；无仿真 RL。

## 13. 开放问题

1. **API 关节顺序**：`action.left_arm`[7] 的索引是否等于数据集数值顺序（URDF 顺序）？必须在调试槽标定。
2. **低层控制器**：joint 目标是直接位置伺服，还是经过 WBC/插值/限幅？DAC 的时间参数化会不会被覆盖？
3. **pivot 语义**：`pivot_3..5` 官方未公开；虽然不等于腰，但是否影响站姿/平衡？默认 0 是否安全？
4. **joint 限幅/拒绝**：evaluator 是否裁剪超限目标？KRA 的 margin 是否足够？
5. **调试槽**：可用次数/成本/是否随机化泛化条件？
6. **WLA 微调**：挑战数据上的 action expert 微调步数/显存/延迟；6B 在目标 GPU 上的 p50/p99。
7. **单模型边界**：KRA/DAC/KRM 确定性代码是否需要在模型卡中逐项披露（倾向：全部披露）。
8. **真实榜单**：发布后重跑“榜首<30%”和任务级归因；预览数字作废。
9. **语言**：评测用 5 条英文复述之一，还是中文/未见复述？SSG 匹配兜底。
10. **外部数据**：比赛期是否允许实验室自采数据？本轮默认不允许，L2L 赛后。
11. **腰**：如果未来 API 开放腰动作，KRA 的腰上界实验可以直接升级；当前不投入。
12. **力/触觉**：如果未来 API 开放，KRM 的残差代理可与力觉融合；当前不投入。

## 14. 一句话押注

**在 30% 天花板下，最值得押注的不是第 14 个语义模块，而是给冻结 VLA 套一层运动学执行层：KRA 把 EE 目标编译成留余量的 7-DOF 关节轨迹，DAC 把 chunk 编译成延迟感知的安全轨迹，KRM 在 chunk 边界用关节残差做接触/限位恢复；腰不可控，所以主战场是手臂冗余和 chunk 时序，不是腰。**
