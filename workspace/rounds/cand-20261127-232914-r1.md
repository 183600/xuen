## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（双足机器人 → 基座是被浪费的「第七轴」，而它是唯一能主动改变泛化几何的动作）**
直觉：大家把 G1 当成一台固定底座的双臂机械臂——`action.pivot` 发零。但双足人形的基座可以动。动基座不是「走路」，而是**重新参数化整个操作问题**：物体太远 / 被遮挡 / 人在旁边，手臂怎么够都别扭；基座往前半步，可达性、视角、与人距离同时改变。五条泛化轴里，位置轴和干扰轴本质是「物体与机器人的相对几何」，而基座是唯一能直接改写相对几何的自由度。更深一层：双足基座是**带支撑多边形、受平衡约束、非完整**的移动机械臂；真正的稀缺资源不是臂长，而是「接触时的稳定裕度」。所以正确的问题不是「怎么伸得更远」，而是「站到哪里，让这个任务又够得着、又看得清、又稳、又离人安全」。
严谨定义：对物体位姿 o 定义**可捕获域** `C(o) = {基座位姿 b : IK 可达 ∧ 可见度 V(b,o)>v ∧ 稳定裕度 S(b)>s ∧ 人机间距 H(b)>h}`。一次「步」= 在安全相位（非抓取 / 非保持的 stance→swing 边界）把 b 离散地移到 b'。步的价值 = Δ(可达+可见+人距的代理分) − λ·时间 − μ·失稳风险；只在价值超阈时迈步，否则零 pivot。用示教学 b 的先验，用 `lower_body` 本体感知估计 S。
反直觉点：**在操作赛里，「走路」的正确用法是「少走、但走对那半步」——基座移动应被视为一种高成本、高杠杆的「主动泛化」，而不是 locomotion。**

**灵感 2（热管理 → 被忽略的第六根轴：不随 episode 重置的隐藏状态）**
直觉：官方五轴（背景 / 光照 / 外观 / 位置 / 人手）都是**外感受、每集重置**的；热不是。热状态跨 episode 累积、路径依赖，而且同时打击两侧：机器人侧，G1 的 QDD 关节持续大扭矩会热降额、限流，甚至「winding overheated」直接关臂（F25）——策略在标称扭矩下学会的动作，在热降额后执行不出来；服务侧，持续推理让 GPU 降频，p99 延迟漂移，正好撞上 README §6 明说要记录的「延迟方差 / 动作规律性」（F21）。所以热管理不是硬件脚注，而是一根**隐藏的耐久轴**：它不改变任务分布，却改变「同一个策略在赛程后段还能不能复现」。
严谨定义：设不可直接观测的关节热状态 τ_t（每关节 + GPU），可用**指令-响应残差**做温度计：低层 PD 下 `τ̂_i ≈ kp_i(q_target,i − q_i) − kd_i q̇_i`，铜损 ∝ τ̂_i²；一阶热模型 `τ̂_{t+1}=a τ̂_t+(1−a)cL_t`，`L_t=Σ τ̂_i²`，a 由散热时间常数定。热降额 `κ(τ̂)∈[κ_min,1]` 缩放加速度 / 瞬态扭矩与保持策略。**关键洞察**：基座靠近物体能减小肩部力臂 → 降低保持扭矩 → 降低铜损——**I10 的「站近一点」同时是 I11 的「少发一点热」**；双臂任务还能在左右臂间倒换负载让一侧冷却。两灵感在此合流：**用身体的空间自由度，去换电机的热预算。**

**两者统一（具身预算）**：前两轮把「信息侧」做到了极致（数据引擎、考纲增广、检索、分级消融）；本轮指出还有两个**物理预算**被纯数据 / 模型路线系统性忽略——空间预算（基座站哪）与热预算（还能撑多久）。它们不增加模型参数，也不改训练分布太多，却直接决定「标称会做的动作在真实赛程里做不做得出来」。

## 2. 对第 2 轮痛点的增量修订

- P2（泛化缺口）新增一条**主动**路径：基座重定位可直接压缩位置 / 遮挡轴的有效偏移；但它自身引入「基座运动」这一新分布，需保守门控。
- P4（无触觉）补充：指令-响应残差（PD 误差）是无传感器下的扭矩 / 接触代理，与 I3 视觉伺服、I2 孪生语料并列。
- P6（部署 / 可信度）升级：热降额导致的延迟漂移 / 动作不规律，是 README §6 可信度评估的直接扣分项 → I6 增加「热稳定」门禁。
- 新增 **P10（pivot 语义与示教覆盖未知）**：`action.pivot` 只有一行文档；示教里可能根本是零。若如此，I10 退化为「手写小步原语 + 单任务通道验证」，不能当主攻。
- 新增 **P11（热效应可能被赛制稀释）**：若每集很短、任务间有自然间隔、N 台机器人轮转，热累积可能不足以影响分数；I11 必须先做「热负载画像 + 单任务长跑」探针，再决定投入。

## 3. 研究问题（本轮立项 Q12–Q14，Q1–Q11 保留）

- **Q12（基座价值）**：32 任务示教中 `action.pivot` 的非零比例与分布如何？哪些任务族（远距 / 遮挡 / 人干扰 / 双臂）从离散基座重定位获得的分数增益最大？如何用可捕获域 + 保守门控学出「只在值得时迈半步」？
- **Q13（热可观测性）**：在只有关节位置 / 末端位姿 / 夹爪 / `lower_body`、无温度 / 电流的接口下，指令-响应残差能否可靠估计热降额？G1 的热时间常数相对单集 / 整场赛程是多少——热效应到底会不会在评测时长内显形？
- **Q14（热感知策略与服务）**：热降额 + 会话级调度（高 / 低负载任务交错、集间微休息、双臂倒换）+ 退化增广训练，能否提升后段成功率 / 步骤分与 p99 稳定性？代价是多少时间？该「把热预算花在难题上」还是「全程保守」？

## 4. 设计原则（新增 PR7、PR8，其余保留）

- **PR7 物理预算律**：每个决策都在花一种物理预算（可达 / 稳定、热、墙钟时间）。按「每单位物理预算换多少分」排序，绝不用不可恢复的物理状态去换分。
- **PR8 隐藏状态跨集耦合律**：任何路径依赖的隐藏状态（热、标定漂移、电量）必须在**会话级**估计与管理；对这些量，episode-i.i.d. 假设无效。与 PR6（本体锚定）互补：PR6 管单帧信任，PR8 管跨集记忆。
- PR1–PR6 保留（第 1 / 2 轮 §4）。

### I4 v2.1 人手干预门控 + 自适应 chunk ★★★★（深化）
- 同第 2 轮：手部检测 + `obs_delta_indices` 历史栈做干预判别（<50ms）；INTERFERED→停持→重估→续做；干预态短 chunk / 稳定态长 chunk。
- **本轮深化（配合 I10）**：让位手段从「停持」扩为两级——①优先停持（零基座运动，最安全）；②若人手持续占据工作空间且停持无法恢复，且稳定裕度 `S(b)>s`、人机间距足够，则**小步后退基座**（远离人，不朝向人），退到 `C(o)` 外沿后重新观测。后退动作必须满足：非接触段、限幅（≤5cm/步）、人不在后退路径上。
- 风险：后退可能把目标移出臂展（缓解：后退后允许一次前向重定位，且后退仅在人干扰轴触发；用 L0 仿真/单任务通道验证「后退→重来」净收益）。

### I5 v2 非标称示教合成 + 得分点对齐恢复 ★★★★（维持）
- 同第 2 轮：扰动重放 / 跨段缝合 / WMA 续写 + 官方得分点里程碑过滤；进度头改得分点监督。
- 本轮补充：热降额后的「动作执行不出来」也可作为 I5 的一种非标称条件——用 I11 的退化增广生成「低扭矩 / 高摩擦」下的恢复示教，与扰动重放共用管线。

### I6 v2.1 确定性低延迟部署服务 ★★★★（深化）
- 同第 2 轮：共享 backend + 每端口独立队列与 episode 状态隔离（F23）、量化、`torch.compile`/CUDA Graph、obs 预取、`image_resize` 压带宽、断线重连 + 健康探针；p99 目标 <40ms。
- **本轮深化（热感知 serving）**：
  1. **GPU 热监控**：用 NVML 读温度 / SM 时钟 / 功耗，按端口记录 p99 与时钟的联合曲线；把「时钟降频 → 延迟上漂」做成可观测告警。
  2. **功耗 / 频率上限**：主动设 `nvidia-smi -pl` 或锁频到「性能足够且不触发热降频」的工作点，换取**延迟方差**下降（README §6 明确看延迟方差，F21）。宁可略慢但稳定，不要忽快忽慢。
  3. **duty-cycle / 批处理**：避免突发高并发；按端口公平调度，防止一个端口的长请求饿死其他端口（F23 并发要求）。
  4. **热稳定门禁**：每次提交前跑「长时压测」——连续 N 分钟满载推理，要求 p99 漂移 <10%、无热降频告警，才允许上计分通道。
- 风险：锁频降低峰值吞吐（缓解：N=3–5 端口、15Hz 参照下 40ms 预算仍有冗余；用实测选工作点，不盲目锁最低频）。

### I7 世界模型测试时前瞻 ★★（缓）（维持）
- 同第 2 轮：高险节点 O(1–2) 次小规模 rollout 择优；第 3 轮基线延迟余量不足即裁撤推理路径，资产转 I5 数据引擎。
- 本轮补充：若 I11 的 serving 侧显示 GPU 热余量紧张，I7 的额外 rollout 是最先该砍的算力开销（与延迟/热双重冲突）。

### I8 v2.2 评测运营闭环 + 分级消融注册表 ★★★★（深化）
- 同第 2 轮：L0 in-silico（免费）/ L1 分数因子 / L2 真机确认 + 离线-在线相关性注册表。
- **本轮深化（控制热混杂）**：热是**会话级路径依赖**，会污染 A/B——若候选 A 总排在赛程前段、候选 B 总排在后段，B 的退步可能来自热而非模块。
  1. **顺序随机化 / 分层**：真机 A/B 的任务顺序随机化，或按热负载分层（高 / 低负载块内比较）。
  2. **热代理作协变量**：每集记录 I11 的 `τ̂`、累计 `L`、GPU 温度 / 时钟，作为回归协变量；报告「控制热后」的增益。
  3. **L1 增列热负载因子**：高 / 低热负载 × 模块 on/off，检验模块是否只在热态下有效（交互项）。
  4. **注册表增列**：`offline_thermal_pred` vs `real_late_session_drop`，用于校准「热计能否预测后段退化」。
- 风险：顺序随机化增加排期复杂度（缓解：先做「热代理记录」这一零成本项，再决定是否分层）。

### I9 v2.1 reset 期检索类比迁移 ★★★★（修正）
- 同第 2 轮：`reset()` 期一次检索，把首帧目标物体映射到「物体-技能库」，episode 内复用动作先验；软偏置 + 距离阈值门控。
- **本轮修正（F22）**：`reset()` 无观测参数、返回平凡确认；首帧在第一次 `get_action` 才到达。伪代码改为**首帧惰性触发**（见 §1.2），不能写 `reset(first_obs)`。
- 风险：同第 2 轮；新增合规确认项不变。

### I10 双足基座主动重定位（footstep-aware manipulation）★★★☆（新增，条件性）
- **动机**：位置 / 遮挡 / 人干扰三轴本质是「物体与机器人的相对几何」；`action.pivot [7]` 已在契约中（F21），是唯一能主动改写相对几何的自由度。大多数队伍把 G1 当固定底座双臂臂，等于放弃这一轴。
- **与现有方案差异**：固定基座 VLA 只能在臂工作空间内插值，遇到远距 / 遮挡只能靠更大的臂展或更聪明的视觉；盲目移动基座又会破坏视觉分布与平衡。本点把基座当**离散、可捕获域约束、只在安全相位**的高杠杆动作，并**默认零 pivot** 的保守门控——只在「够不着 / 看不清 / 人太近」时迈最小半步。
- **技术可行性**：中。先做离线审计（示教 pivot 分布 + IK 可达图），再做单任务通道小步探针；可捕获域用解析 IK / 碰撞 + 现成检测，不需新模型。最大不确定性是 pivot 语义（F26）。
- **所需资源**：离线审计 2 人日；单任务通道 2 任务 × 各 3 次；无额外 GPU。
- **落地步骤**：
  1. **示教审计**：统计 32k 示教 `action.pivot` 的均值 / 方差 / 非零比例；若全零，记为「无示教先验」，I10 降级为手写原语。
  2. **语义探针**：在单任务通道对 1 个远距 / 遮挡任务发 ±2cm / ±5° 小 pivot，确认基座是否响应、动作是否被接受、成功率 / 步骤分是否变化（先只做平移，不做转向）。
  3. **可捕获域代理**：用末端位姿 + 物体检测估计 reach margin 与可见度，用 `lower_body` 估计稳定裕度。
  4. **stance/swing 状态机**：仅在「未抓取、未保持、已到安全位」时允许迈步；抓取 / 保持 / 接触段锁死基座。
  5. **保守策略**：默认 `b=b0`；仅当 reach margin < 阈值或可见度 < 阈值或人距 < 安全阈值时，选 `C(o)` 内离 b 最近的 `b'`，小步移动；移动后**重新观测再抓**（把基座运动段当独立「导航小段」，操作段仍用标称分布）。
  6. **与 I4 联动**：人手持续占据且停持无效时，基座后退让位（需稳定裕度与人距门控）。
- **风险**：pivot 语义 / 示教覆盖未知（缓解：先探针，未验证不上主链）；移动基座使相机分布外移（缓解：移动后重新观测，操作段不混入运动帧）；平衡不可观测（缓解：`lower_body` + 保守小步 + 仅在 stance 动）；评测可能不鼓励移动（缓解：默认零 pivot，收益不显著即砍）。

### I11 热感知耐久策略与服务 ★★★★（新增）
- **动机**：G1 热降额 / 关臂是已记录硬约束（F25）；赛程是长跑，热跨集累积；README §6 可信度直接看延迟稳定（F21）。纯标称训练的策略在后段可能「会做但做不动」。
- **与现有方案差异**：现有方案假设执行器恒扭矩、服务恒频率；本点显式建模并管理两个热预算（关节 + GPU），把「休息 / 降额 / 换臂 / 站近」当动作。关键耦合：**基座靠近 = 减小肩部力臂 = 降低保持扭矩 = 降低铜损**（I10 × I11），双臂任务可左右倒换负载让一侧冷却。
- **技术可行性**：中。指令-响应热计只用现有通道（关节位置 + 指令，F20/F24；速度用历史栈差分）；一阶热模型简单；退化增广是数据工程；serving 监控用 NVML。
- **所需资源**：离线画像 2 人日（零 GPU）；退化增广训练 1×24GB；单任务长跑 1 任务 × 连续 10–20 集；serving 监控 1 人日。
- **落地步骤**：
  1. **离线热负载画像**：从 32 任务示教用 `τ̂≈kp(q_target−q)−kd q̇` 算每任务 `L_t` 与累计热，排出「热贵任务」榜；同时算基座距离对肩部力矩的影响。
  2. **热计校准**：一阶模型 + 残差漂移项；单任务通道连续跑，记录「同样指令下末端跟踪误差 / 到达时间」是否随集数漂移（执行器自己就是温度计）。
  3. **退化增广**：训练时随机降低有效扭矩上限、加响应滞后、加摩擦 / 零位漂移，模拟热降额；让策略不依赖峰值扭矩。
  4. **会话调度**：按热负载榜交错高 / 低负载任务；集间插入最短必要休息（若赛制允许）；双臂任务做负载倒换；热预算紧张时优先「站近一点」而非「硬拉」。
  5. **热感知 serving**：同 I6 v2.1（GPU 温度 / 频率 / 功耗上限 / duty-cycle）。
  6. **门禁**：只有「热计能预测后段退化」且「降额 / 调度在单任务长跑上净增益 >0」才放量。
- **风险**：单集短 / 任务间自然冷却 → 热效应不显形（缓解：先画像 + 长跑探针，未显形则只保留 serving 侧）；热计不可观（缓解：多信号融合 + 保守阈值，宁可早降额）；降额降低速度伤时间分（缓解：只降瞬态加速度、保保持力，且用基座靠近降低所需扭矩）；过度工程（缓解：先做零成本的离线画像）。

### 1.1 基座可捕获域与保守迈步（I10）

```python
class FootstepGate:
    """默认零 pivot；只在够不着/看不清/人太近时迈最小半步。"""
    def should_step(self, obs):
        if self.in_contact or self.holding:      # 接触/保持段锁死基座
            return False
        margin = reach_margin(obs)               # 末端到目标的可达余量
        vis    = visibility_score(obs)           # 目标可见度（检测置信/遮挡）
        human  = human_clearance(obs)            # 人机距离（I4 复用）
        stable = stability_margin(obs["observation.state.lower_body"])
        if stable < S_MIN:
            return False
        return (margin < M_LO) or (vis < V_LO) or (human < H_MIN)

    def propose(self, obs):
        b_cur = base_pose_from(obs)
        cands = capture_region(obs, b_cur)       # IK∧可见∧稳∧人距
        if not cands:
            return None                          # 无可捕获位：宁可不迈
        b_best = min(cands, key=lambda b: dist(b, b_cur))  # 最小步
        return small_pivot(b_cur, b_best)        # 限幅，平移优先，不朝向人
```

class RetrievalAugmentedPolicy:                  # 唯一参赛实体：一个 PolicyService
    def reset(self):                             # 官方：无参数、每集一次（F22）
        self.prior = None
        self._first_done = False

    def get_action(self, obs):
        if not self._first_done:                 # 首帧在这里才到达（F22）
            self._build_prior(obs)
            self._first_done = True
        chunk = self.vla.propose_chunk(obs, prior=self.prior)
        return self.guard_stack(chunk, obs)

    def _build_prior(self, obs):
        obj = detect_object(obs["observation.images.cam_left_high"], self.lang)
        emb = embed(obj.crop)                    # DINOv2 池化 + 指令嵌入
        hit = self.index.search(emb, k=3)        # 物体-技能库（110 语料）

### 1.3 指令-响应热计与降额（I11）

```python
# 只用可用通道：关节位置（可多帧堆叠，F24）、动作指令、已知低层 PD 增益。
def torque_proxy(q, qd, q_target, kp, kd):
    return kp * (q_target - q) - kd * qd        # 低层 PD 的扭矩代理

def thermal_load(obs, act, kp, kd):
    q  = obs["observation.state.left_arm"]       # 取最新帧
    qd = finite_diff(obs["observation.state.left_arm"])  # 历史栈差分
    tau = torch.cat([torque_proxy(q, qd, act["action.left_arm"], kp, kd),
                     torque_proxy(qr, qdr, act["action.right_arm"], kp, kd)])
    return float((tau ** 2).sum())               # 铜损代理 ∝ I² ∝ τ²

class ThermalBudget:
    def __init__(self, a=0.995, soft=0.6, hard=1.0, kmin=0.6):
        self.tau_hat, self.a = 0.0, a
        self.soft, self.hard, self.kmin = soft, hard, kmin
    def update(self, L):
        self.tau_hat = self.a * self.tau_hat + (1 - self.a) * L
    def derate(self):
        k = 1 - (self.tau_hat - self.soft) / (self.hard - self.soft)
        return max(self.kmin, min(1.0, k))       # 缩放瞬态加速度，保保持力
    def schedule(self, tasks):
        return interleave_by_load(tasks, self.load_profile)  # 高/低热负载交错
```
