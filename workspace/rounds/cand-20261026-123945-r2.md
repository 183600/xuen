# 第 8 轮 · CO-HASM：人为干扰是隐藏的 20%，状态机是人机共处的接口

> 检索/复核日期：2026-10-26（UTC）。赛事身份不变：宇树科技 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型、选手自部署 + 官方远程真机 API。本轮三个灵感词是「人机协作」「用户测试」「状态机」。我先做了一次规则纠偏，再把三个词钉到本轮核实到的官方事实上，最后合成主判断：**官方 33k 演示基本是“无人干扰”的干净遥操作，而评测里人为干扰轴占每任务 2/10 = 20% 的试次；这是当前头部方案（榜首 29.7%）最可能集体失分、也最容易被忽视的分数池。用“可中断/可回滚的人机共处状态机（CO-HASM）”在运行时让行、跟踪、恢复；用“状态机覆盖率为目标的人类用户测试（HUT）”采集官方数据里完全缺失的人为干扰数据；用公开示例备注做类型先验。** 这不是第 7 轮 NRB 的重复：NRB 是离线合成“破坏→恢复”对；本轮是运行时人-机共处 + 真实人类用户测试 + 状态机覆盖。

## 0. 本轮先纠偏：三条硬事实改变了上一轮的算盘

### 0.1 排名首先看成功率，步骤分只是同分 tie-break

官方参赛手册（中/英 Feishu，2026-10-26 读取，[S2]）写得很清楚：

> “实时榜单按 32 个任务的总平均成功率进行排序，成功率相同时按总平均步骤分排序，若仍相同，则提交日期较早的模型排序靠前。”

上一轮把“终局放置≈60% 步骤分”当成与成功率并列的主目标，是**过度加权**。步骤分仍然重要，但它的正确位置是：(a) 诊断“钱丢在哪一步”；(b) 同分时的 tie-break；(c) 成功率的分解指标。**排名的一阶目标是成功率，不是部分分。** 这直接改变了资源分配：不该再把大量预算花在“多做半步拿部分分”上，而该花在“让整条 episode 走到成功”上。

### 0.2 每任务 10 次 = 5 类泛化 × 2；人为干扰占 20%

同一份手册 [S2]：

> “每个任务执行 10 次独立运行……10 次运行中包含以下 5 种泛化类型，每种类型各出现 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。”

因此人为干扰不是“偶尔出现的噪声”，而是 **32 任务 × 2 次 = 64 次试次，占 320 次总试次的 20%**，且在每个任务内部都占 2/10。**这是唯一一个在所有任务上都有固定权重、但官方训练数据里没有对应片段的轴。** 位置/干扰物/背景/未见物品都能在 33k 干净演示里找到近似；人为干扰没有。

### 0.3 公开的 human_1/human_4 更像“示例视频标注”，不是评测剧本

我抽查了 T01/T07/T10/T12/T14/T16/T17/T18/T19/T24/T25/T26/T27/T31/T32 的 `tasks_v2/<slug>/info.json`（[S3]）。每个文件的 `episodes` 数组恰好有 5 个示例（index 0–4），而 `generalization` 的键名落在 `unseen_object_3`、`human_1_note`、`human_4_note` 上——**最合理的解释是它们标注第 2/4/5 段示例视频，而不是 10 次评测的试次安排**。上一轮把“官方备注=评测剧本”说得太满，本轮降级为“**人类干扰的类型先验**”：备注告诉我们人类会“平移物体”或“撤销已完成步骤”，但不保证评测照搬。这个纠正反而加强了用户测试的必要性——**既然剧本不公开，就只能用真实人类采样一个分布**。

### 0.4 榜单：8 个模型已展示，但底层仍是占位

`leaderboard.html` 现在展示 8 个模型，榜首 MolmoAct2/DexHacker 为 **29.7% / 39.0**，与用户“榜首不到 30%”的前提一致（[S7]）。但同一页面的 `leaderboard_data.json` 仍写着 `generated_from: gen_leaderboard.py`，详情页视频仍是“测试视频占位”，`runs.html` 仍是 256/256 的模板填充（[S8]）。**因此这些数字只能当“难度/结构先验”，不能当真实排名；真实 human 轴基线必须用调试槽校准。**

## 1. 三个灵感词，各自钉到事实上

### 1.1 人机协作 → 不是“协作任务”，而是“共享工位里的同事”

UniBot 没有人类-机器人协作任务；唯一的“人”是人为干扰轴里的干扰者。最贴切的 HRI 角色是 HABIT（[S10]）定义的 **Coworker**：人和机器人在同一空间各做各的事，机器人必须学会 **yielding（让行）**。HABIT 的 10K episodes / 160h / 60 tasks 证明了一件事：**只在无人数据上训练的策略，不会自发出现 human-aware 行为**。这正好解释了为什么 33k 干净演示训出来的头部模型，遇到 human 轴可能接近失明。

所以本轮把“人机协作”重新定义为 **人机共处（co-presence）**：干扰者是一个“带隐藏脚本的同事”。机器人不需要读懂人心，只需要：
- 检测人手/手臂进入共享工作区；
- 在冲突前减速/让行/保持抓取；
- 人走后重新定位、检查谓词、必要时回滚重做。

这是一种**隐式协作**：不对话、不接管，只共享空间与状态。

### 1.2 用户测试 → 官方数据缺的那一块，只能用真人补

官方 33k 是遥操作演示，采集时没有人进入桌面工作区；它覆盖位置/干扰物/背景/未见物品，但**没有“人手伸进来把物体拿走/把拉链拉开/把瓶盖拧回去”的片段**。合成扰动可以补一点，但人手的外观、速度、时机、遮挡、意图都太真实，纯合成会有域差。

因此本轮把“用户测试”做成一个**数据引擎 + 评测协议**：
- 招募非专家用户，按“平移/撤销/拿走/移动底座/动态目标”五类脚本，在真实 G1 桌面上干扰机器人；
- 记录四路相机、关节/EE、HSM 状态轨迹、谓词、结果、恢复动作；
- 用**状态机覆盖率**决定下一批测什么：哪些 hazard transition 还没被覆盖，就优先测哪个；
- 同时做一个小型 HRI 用户研究：让用户评价机器人的让行是否可理解、是否安全（NASA-TLX/信任/安全感），作为辅助指标。

这比“再采 1 万条干净演示”更划算：**干净数据已经饱和，human 数据是零**。

### 1.3 状态机 → 从“线性步骤图”升级为“可中断、可回滚的分层状态机”

第 7 轮的 SSG 是一条 `s0→s1→…→sk` 的线性评分步骤图，只解决“别跳步/别假完成”。但 human 轴的核心事件是 **中断（interrupt）** 和 **撤销（undo）**：人手进来、物体被移走、已完成的步骤被倒回去。线性图没有“人在场”这一维，也没有“回滚栈”。

本轮升级为 **CO-HASM**：一个带正交区域的分层状态机（statechart）：
- **任务区**：官方 score_steps 编译出的 `S0..Sk`；
- **人类区**：`ABSENT / APPROACH / ACT / LEAVE`；
- **恢复区**：`NOMINAL / DIAGNOSE / REPAIR / RETRY / ABORT`；
- **安全区**：`SAFE / SLOW / STOP`。

转移在 **action chunk 边界** 求值；恢复用“完成栈 + 最小回滚”：只回退到最早失效的那一步，不整题重来。这个结构直接对应评测里的 5 类 human 干扰剧本，也天然可测试、可可视化、可算覆盖率。

## 2. 主判断：human 轴是隐藏的 20%，也是头部方案的共同盲点

### 2.1 算术

设 human 轴成功率为 h，其余四轴平均为 o：

```text
总成功率 = 0.2 h + 0.8 o
```

如果榜首 29.7% 且 h≈0，则 o≈37.1%；如果 h≈10%，则 o≈34.6%。**把 h 从 0–10% 拉到 30–50%，总成功率约 +5～10pp。** 对照：把其余四轴整体拉 5pp，只 +4pp；把终局放置整体拉 5pp，约 +5pp（因为它是成功闸门）。**human 轴的杠杆与“全局终局放置”同级，但它的数据缺口更大、竞争者更少、评测权重固定 20%。**

### 2.2 为什么头部方案可能集体失分

- 33k 演示是干净遥操作，没有 human 片段（HABIT 的证据：无人数据不产生 human-aware 行为）；
- 头部模型是通用 VLA/世界模型，训练目标是“从初始状态到成功”的轨迹拟合，不是“被中断后恢复”；
- RoboRecover（[S12]）证明：**初始状态的成功率不能预测恢复成功率**，恢复是独立能力；Recova（[S11]）也证明恢复需要单独的策略/程序与验证；
- 因此“通用模型很强”不等于“human 轴很强”。这 20% 很可能是一个被平均分掩盖的结构性缺口。

### 2.3 与终局放置的关系

终局放置仍然是**成功闸门**，但它不再是本轮的主叙事。它被吸收进 CO-HASM 的“任务区 + 恢复区”：PGL/OPT/SVL 继续作为放置技能组件，服务“回滚后重做”和“被人移动后重新放”。**资源从“部分分优化”转向“整条 episode 的成功率”，尤其是 human 轴的 20%。**

## 3. 方案轮廓：CO-HASM + HUT

```text
官方 score_steps + 5 复述 + 示例 human 备注
        │
        ▼
S2H 编译器：步骤→技能模板→谓词→hazard 标注→HSM YAML
        │
        ▼
┌──────────────── CO-HASM（运行时，chunk 级）────────────────┐
│ 任务区 S0..Sk   ← 谓词/完成栈                              │
│ 人类区 ABSENT/APPROACH/ACT/LEAVE ← 手/物检测 + 脚本先验    │
│ 恢复区 NOMINAL/DIAGNOSE/REPAIR/RETRY/ABORT ← 最小回滚      │
│ 安全区 SAFE/SLOW/STOP ← 人-机距离/速度/抓取体积            │
└────────────────────────────────────────────────────────────┘
        │
        ▼
单一 checkpoint：WLA-1.0-Base + 步骤谓词头 + 人手/物关系头
        │
        ├── 正常：VLA action chunk（EE 空间）
        ├── 人在场：让行/保持/后退（解析 primitive）
        └── 人撤销：回滚到最早失效步骤 → VLA 重做
        ▲
        │
HUT 用户测试：真实人类干扰 → 覆盖率/失败矩阵 → 训练数据
```

**一句话：把评分步骤编译成状态机，把人类干扰当作状态机的第一类事件，把用户测试当作 human 轴的数据引擎。**

## 4. 与第 7 轮的关系

| 关系 | 内容 |
|---|---|
| 纠偏 | 步骤分从“共同目标”降为“诊断 + tie-break”；human 轴从“备注剧本”升级为“20% 隐藏分数池” |
| 保留 | SSG 的任务层、SVL 的落点校验、PGL/OPT 的放置技能、GPR-VLA/WLA 底座、TLE/ACP/GF、Endurance Governor |
| 升级 | SSG → CO-HASM；NRB → 示例类型先验 + 真实 human 数据；L2L → 用户测试农场；DebugLoop → human 轴专用 |
| 新增 | S2H 编译器、CO-HASM 运行时、HUT 数据引擎、human-aware head、完成栈/最小回滚、覆盖率指标、chunk 级反应约束 |
| 修剪 | “步骤分 60%”作为排名论据；“官方备注=评测剧本”；纯合成 human 恢复；每任务 LoRA；全 32 任务高保真孪生 |

## 5. 风险与合规（先立后破）

- **human 检测误判**：保守减速/停止；classical hand detector 兜底；用用户测试数据校准。
- **chunk 反应太慢**：`action_chunk_size` 选 4–8（30Hz 下 133–267ms）；人靠近时返回安全 chunk；必要时蒸馏小模型。
- **状态机脆**：谓词置信度低时回退到 VLA；回放测试；不要硬编码所有任务。
- **评测剧本未知**：用户测试采样“平移/撤销/拿走/移动底座/动态目标”五类，不押单一备注。
- **单模型审计**：HSM 是确定性代码；human head 放进同一 checkpoint；模型卡写清；备选方案是纯 classical 检测。
- **外部数据**：自采 human 数据默认只用于验证；训练前发邮件确认；若禁止，则用合成 + 官方数据，HSM 仍可工作。
- **安全/伦理**：用户测试需知情同意、去脸、可退出；机器人限速、保持退路、急停；不让用户处于夹爪闭合体积内。
- **榜单仍是占位**：不把 29.7% 当真实基线；用 debug slot 校准 human 轴。

## 6. 一句话押注

**把人为干扰轴当作隐藏的 20% 分数池：用“可中断/可回滚的人机共处状态机（CO-HASM）+ 以状态机覆盖率为目标的人类用户测试（HUT）”把它从近零拉到 30–50%，整体成功率 +5～10pp——这比继续在干净数据上抠终局放置更可能越过头部的 29.7%。**

# 第 8 轮产物区 · CO-HASM 技术报告（人机共处状态机 + 用户测试数据引擎）

> 目标赛事：宇树科技 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。检索/复核日期：**2026-10-26（UTC）**。本报告在第 7 轮 PILOT-GPR 基础上做一次“规则纠偏 + 主目标切换”：**官方参赛手册明确排名首先按 32 任务总平均成功率，步骤分只在同分时 tie-break；同时人为干扰轴固定占每任务 2/10 = 20% 的试次，而官方 33k 演示是干净遥操作、没有对应的 human 干扰片段。** 因此本轮把主战场从“终局放置的部分分”移到“human 轴的整条 episode 成功率”，提出 **CO-HASM**（Coworker-Aware State Machine）+ **HUT**（Human-disturbance User Testing）。

---

## 0. 产物摘要

### 0.1 一句话

**把人为干扰轴当作隐藏的 20% 分数池：用“可中断/可回滚的人机共处状态机（CO-HASM）”在运行时让行、跟踪、恢复；用“以状态机覆盖率为目标的人类用户测试（HUT）”采集官方数据里完全缺失的 human 干扰数据；用公开示例备注做类型先验。目标是把 human 轴从近零拉到 30–50%，整体成功率 +5～10pp。**

### 0.2 组件与是否进推理

| 组件 | 作用 | 进推理？ |
|---|---|---|
| S2H 编译器 | 官方 score_steps + 示例备注 → HSM YAML；步骤→技能模板→谓词→hazard 标注 | 否（离线编译，产物是代码/配置） |
| CO-HASM 运行时 | 任务区/人类区/恢复区/安全区的分层状态机；chunk 边界求值 | 是（确定性代码） |
| Human-aware head | 人手/手臂检测、物体归属、干扰类型、time-to-contact | 是（同一 checkpoint 的辅助头） |
| Step predicate head | 每步完成概率；成功闸门与回滚触发 | 是（同一 checkpoint 的辅助头） |
| VLA 动作专家 | 局部接触丰富技能；EE 空间 action chunk | 是（唯一动作模型） |
| 完成栈 + 最小回滚 | 记录已完成步骤；人撤销时回退到最早失效步 | 是（确定性代码） |
| 恢复 primitive 库 | SAFE_RETREAT / HOLD_WAIT / RE_LOCALIZE / RE_GRASP / RE_PLACE / RE_DO_STEP | 是（解析/脚本 primitive） |
| HUT 数据引擎 | 真实人类干扰的用户测试；覆盖率/失败矩阵 | 否（训练与验证数据） |
| NRB-lite | 官方示例备注 → 合成“破坏→恢复”对 | 否（训练数据，降为辅助） |
| DebugLoop | 单任务调试槽作 human 轴发布门 | 否（流程） |
| API 状态机 | handshake/reset/act/timeout/error 的生命周期守卫 | 是（服务端工程代码） |

### 0.3 预期收益（可证伪）

- 官方权重：human 轴 = 2/10 = 20%；设 human 成功率 h、其余四轴平均 o，则 `总成功率 = 0.2h + 0.8o`。
- 若榜首 29.7% 且 h≈0–10%，则 o≈34.6–37.1%；**h 提升 25pp → 总成功率 +5pp；h 提升 40pp → +8pp**。
- 对照：其余四轴整体 +5pp 只 +4pp；终局放置整体 +5pp 约 +5pp。**human 轴与“全局终局放置”同级，但数据缺口更大、竞争者更少。**
- 可证伪点：若 HUT 后 human 轴提升 <10pp，或 human 检测 F1 <0.6，则 CO-HASM 假设不成立，回退到“保守减速 + VLA-only”并转攻其他轴。

### 0.4 与上一轮（PILOT-GPR）的关系

| 关系 | 内容 |
|---|---|
| 纠偏 | 步骤分从“共同目标”降为“诊断 + tie-break”；human 轴从“备注剧本”升级为“20% 隐藏分数池” |

## 1. 事实核对（2026-10-26）

### 1.1 官方手册：10 次/任务、5 类×2、成功率优先

官方参赛手册（中/英 Feishu，[S2]）给出了本轮最重要的三条规则：

1. **每任务 10 次独立运行**，包含 5 种泛化类型，每种 2 次：位置、干扰物、桌面背景、未见物品、人为干扰。
2. **排名首先按 32 任务总平均成功率**；成功率相同按总平均步骤分；仍相同则提交日期早者靠前。
3. **每任务单次真机执行最大 180 秒**，超时记为失败；成功=所有步骤完成，步骤分按完成情况计算。

原文（英）：

> “Each task is executed 10 times independently… the 10 runs include the following 5 generalization types, each appearing twice.”
>
> “The real-time leaderboard is sorted by overall average success rate across all 32 tasks. In the event of a tie, the overall average step score is used as the differentiator. If still tied, earlier submission dates rank higher.”
>
> “The maximum allowed execution time for a single real-machine run per task is 180 seconds.”

这纠正了第 7 轮的一个隐含假设：**步骤分不是与成功率并列的一阶目标，而是 tie-break 与诊断指标。** 第 7 轮的“终局放置≈60% 步骤分”仍有诊断价值（它告诉你失败发生在哪），但不能作为“应该把 40% 预算投给放置”的排名论据。

### 1.4 数据与接口

- **数据规模**：官方挑战页写 32 任务 / 32,000 演示 / 169 小时（[S1]）；HF collection 32 个数据集（[S5]）；HangCup 实测 1,043 episodes / 194,564 frames / 30fps，`lastModified` 2026-10-14（[S6]）。
- **数据内容**：LeRobot v3；四路相机 `head_stereo_left/right` + `wrist_left/right`；EE 位姿在 base 与 torso 两套坐标；夹爪开度；lower_body；`state_d435`；动作含 EE/joint 两套。数据集卡片见 [S6]。
- **接口（[S4]，v2 提交 2026-08-21）**：
  - 观测：4×RGB 480×640、双臂关节/EE、夹爪、lower_body、`observation.language` 单字符串（episode 内不变）。
  - `obs_delta_indices`：选择传哪些键 + 每键堆叠几帧；语言必须 `[0]`。
  - `image_resize`：每路图像的目标分辨率；评测端用 `cv2.resize`。
  - `action_chunk_size`：每次 `get_action` 返回的动作步数；动作数组形状 `(T_a, …)`。
  - 动作空间：joint 或 ee 互斥；共享 `left_gripper/right_gripper/pivot`。
  - `reset()` 每 episode 一次；token 在 `metadata` 与每个 `meta.token` 双处校验。

**接口层面的关键含义：**

- 我们可以在观测里做**人手/物体 overlay**、时间堆叠、分辨率裁剪；这给 human-aware head 提供了输入自由度。
- 动作 chunk 是**开环执行**的：策略返回 chunk 后，评测端按顺序执行，直到下一次 `get_action`。因此 human 轴的反应延迟下界约等于 chunk 时长 `T_a/30s`。这是本轮新增的硬约束（见 §4.6）。
- `control_space=ee` 适合让行、后退、重新定位、重新抓取；joint 更适合全身/柔顺，但恢复 primitive 用 EE 更直接。建议 EE。

## 2. 评分算术：为什么 human 轴是隐藏的 20%

### 2.1 总成功率的分解

官方：32 任务 × 10 次 = 320 次；human 轴每任务 2 次 = 64 次 = 20%。

```text
Overall = (1/32) Σ_t [ (1/10) Σ_{a=1..5} Σ_{r=1..2} success(t, a, r) ]
        = 0.2 * h + 0.8 * o
```

其中 h 是 human 轴平均成功率，o 是其余四轴平均成功率。

### 2.2 提升 human 轴的杠杆

| 场景 | 假设 | 总成功率 | 相对 29.7% |
|---|---:|---:|---:|
| 基线 | h=0, o=37.1 | 29.7 | — |
| human +10pp | h=10, o=37.1 | 31.7 | +2.0 |
| human +25pp | h=25, o=37.1 | 34.7 | +5.0 |
| human +40pp | h=40, o=37.1 | 37.7 | +8.0 |
| 其余四轴 +5pp | h=0, o=42.1 | 33.7 | +4.0 |
| 终局放置 +5pp | 全部轴 × 闸门 | ≈34.7 | +5.0 |

> 注：基线 h=0 只是上界情景；真实 h 未知。若 h 已经是 20%，则同样的 +25pp 目标变成 45%，增益仍是 +5pp。关键是 **human 轴的权重固定 20%，而它的数据供给是零**。

### 2.3 统计噪声

- 320 trials，若 p≈0.30，SE≈√(0.3×0.7/320)=2.56pp。**+5pp 约 2 SE，+3pp 约 1.2 SE**；需要 320 trials 才能有基本的区分力。
- human 轴 64 trials，若 p≈0.30，SE≈5.7pp；**+25pp 约 4.4 SE**，在 aggregate 层面可检测。但单任务只有 2 次 human trial，单任务层面几乎不可检测；必须跨任务聚合或用 HUT 的 100–200 episodes 做可靠估计。
- 排行榜 #1 与 #2 只差 1.2pp，远小于 SE；**不要根据占位榜的微小差距做决策**。+5pp 才是统计上可辩护的目标。

### 2.4 为什么不再把步骤分当主目标

- 步骤分只在成功率相同时 tie-break；为了 +5 步骤分而牺牲 1pp 成功率是亏的。
- 但步骤谓词仍然关键：它是**成功判定、回滚触发、失败诊断**的基础。所以我们保留 SSG 的谓词，不保留“为部分分而设计”的预算逻辑。
- 终局放置仍然是成功闸门；它被吸收进 CO-HASM 的任务层/恢复层，而不是单独的主战场。

## 3. 头部方案与瓶颈

### 3.1 头部模型类型

- **VLA 系**：MolmoAct2（#1）、WALL-OSS-0.5（#2）、Spirit-v1.5（#4）、PI-0.5（#6）、GigaBrain-0（#7）、GR00T N1.5（#8）。
- **世界模型系**：DreamZero（#3）。
- **混合/机构系**：DM0（#5）。
- 结论：**通用 VLA 仍是头部主流；世界模型有竞争力但不统治；没有 human-aware 系统进入头部。**

### 3.2 共同盲点

1. **训练数据干净**：33k 遥操作演示，没有人进入工作区；HABIT 证明无人数据不会自发产生 human-aware 行为。
2. **没有显式状态**：端到端 VLA 把“做到哪一步”隐式编码在隐状态里；被人撤销后，模型可能继续按原计划走。
3. **没有恢复机制**：RoboRecover 证明初始成功率不预测恢复成功率；Recova 证明恢复需要单独的策略/程序与验证。
4. **chunk 开环**：动作 chunk 在执行期间不可中断；human 轴需要更短的反应粒度。
5. **没有 human 轴评测信号**：榜单只报总体成功率/步骤分，不报轴级；团队很难知道自己在 human 轴上有多差。

### 3.3 证据链

| 证据 | 关键结论 | 对本方案的意义 |
|---|---|---|
| HABIT [S10] | 10K episodes / 160h / 60 tasks；human-present 数据才能诱发 yielding/synchronization/gesture grounding | human 轴必须补真人数据；Coworker 角色最贴切 |
| RoboRecover [S12] | 2,000 scenarios；初始状态成功率不能预测恢复成功率 | 恢复是独立能力；要单独测/训 |

| B2FF [S18] | 用“熟悉的未来”做恢复条件；56.3→74.0 | 恢复可以用视觉目标引导 |
| Hide-and-Seek [S19] | 轨迹级弱监督的失败信号 | 不需要步级标注也能做失败检测 |

| VLA-FixBench [S21] | VLM 诊断/修复 VLA 故障 | 故障分类+修复是独立研究面 |

| H2RBench [S25] | human-to-robot transfer 的 real2sim 基准 | 人类视频/数据可用于预训练，但不能替代真机 human 轴 |

### 3.4 仍然缺失的东西（本轮的 gap）

- 没有公开工作把 **UniBot 的 score_steps 编译成 HSM**；
- 没有公开的 **G1 Dex1 human-interference 数据集**；
- 没有把 **人为干扰轴 20% 权重** 显式纳入策略设计的工作；
- 没有 **状态机覆盖率驱动的人类用户测试** 协议；
- 没有把 **chunk 反应延迟** 当作 human 轴的一等约束来分析。

这五个缺口就是本轮的创新空间。

## 4. CO-HASM 架构

### 4.1 总览

```text
┌──────────────────────── Offline ────────────────────────┐
│ 官方 info.json（score_steps / generalization / episodes） │
│ 33k 干净演示（LeRobot v3）                                │
│        │                                                 │
│        ▼                                                 │
│ S2H 编译器：步骤→技能模板→谓词→hazard→HSM YAML           │
│        │                                                 │
│        ▼                                                 │
│ HUT 用户测试：真实人类干扰 → 覆盖率/失败矩阵/训练数据     │
└──────────────────────────────────────────────────────────┘
                           │
┌──────────────────────── Online ─────────────────────────┐
│ obs（4 相机 + proprio + language）                        │
│        │                                                 │
│        ├─► Human-aware head：手/物/类型/TTC/置信度        │
│        ├─► Step predicate head：P(step complete)          │
│        └─► VLA action expert：EE chunk                    │
│        │                                                 │
│        ▼                                                 │
│ CO-HASM：任务区 × 人类区 × 恢复区 × 安全区                │
│   ├─ 正常：执行 VLA chunk                                 │
│   ├─ 人靠近：SAFE_RETREAT / HOLD_WAIT / SLOW              │
│   ├─ 人移物：RE_LOCALIZE / RE_TARGET                      │
│   ├─ 人撤销：完成栈回滚 → RE_DO_STEP                      │
│   └─ 超时/失败：ABORT / 保留部分分                        │
└──────────────────────────────────────────────────────────┘
```

### 4.2 任务层：S2H（Score-Step-to-HSM）编译器

**输入：**

- `info.json` 的 `score_steps`（有序步骤 + 分值）；
- `en_desc` / 5 条英文复述；
- `generalization` 的 human/unseen 备注；
- 33k 演示的帧、EE 位姿、夹爪、语言。

**输出：**

- 每任务一个 HSM YAML：状态、转移、guard、超时、恢复动作；
- 每步一个谓词头训练标签；
- 每任务一个 hazard 表：哪个物体、哪个步骤、哪类干扰、期望恢复；
- 覆盖率矩阵的初始目标集合。

**编译步骤：**

1. **技能分类**：把每个 step 文本映射到固定技能本体（grasp / place / insert / open / close / zip / stack / pour / pick_out / flip / press / pull / push / handover）。用 LLM + 人工复核，32 任务只需一次。
2. **谓词归纳**：对每一步，确定“必须成立的关系”（物体在容器内、夹爪闭合且接触、拉链闭合、插头到位、堆叠稳定）。用演示帧 + 几何特征 + 少量 VLM 标注拟合；阈值用演示分布的分位数。
3. **相位对齐**：用 TLE（第 5 轮）或简单的速度/接触变化把演示切到步骤；给谓词头提供正负样本。
4. **hazard 标注**：把 human 备注映射到“受影响步骤 + 物体 + 干扰类型 + 恢复动作”。例如 T27 human_4“叠了第二个之后拿下第二个” → 在 S2（bowl2 stacked）上标注 `UNDO_STEP(bowl2)`，恢复为 `ROLLBACK(S1) → RE_DO_STEP(S2)`。
5. **HSM 生成**：每个步骤一个状态；每个 hazard 一个中断转移；每个恢复 primitive 一个动作节点；安全区独立。
6. **验证**：在演示上回放，检查 HSM 是否按正确顺序推进；在 HUT 回放上检查 hazard 转移是否被触发；输出覆盖率报告。

### 4.3 人类层：检测 + 类型先验 + 意图

**输入：** 4 路 RGB（头双 steres + 双腕）、EE 位姿、夹爪、最近 N 帧（`obs_delta_indices` 堆叠）。

**输出：**

- 人手/手臂的 2D/3D 关键点或热图；
- 手附近的物体（object ownership）；
- 干扰类型（6 类原语 + `NONE`）；
- time-to-contact（TTC）：手到机器人计划路径/目标物体的预计时间；
- 置信度。

**检测路线（按优先级）：**

1. **同一 checkpoint 的 human-aware head**：在 VLA 的视觉 token 上加一个轻量 transformer/MLP，输出手部热图、物体归属、类型、TTC。优点是单模型合规、端到端；缺点是需要 human 数据训练。
2. **classical 兜底**：MediaPipe Hands / YOLO-pose / 肤色+深度+光流；头双 steres 可三角化 3D。优点是零训练、可解释；缺点是对遮挡/快速运动不稳。
3. **融合**：head 置信度高用 head；低置信度用 classical + 保守减速。

**类型先验（来自示例备注，不是剧本）：**

| 类型 | 触发线索 | 机器人应对 |
|---|---|---|
| MOVE_TARGET | 目标物体被手抓住并平移 | 等待/跟踪；人停后重新定位，更新目标位姿，继续 |
| UNDO_STEP | 已完成步骤的谓词从 1→0（拉链被拉开、碗被拿走、瓶盖被拧回） | 回滚到该步，重做 |
| REMOVE_OBJECT | 目标/工具被拿离工作区 | 保持/等待；人放回后重新抓取；若超时则 ABORT |
| MOVE_SUPPORT | 底座/架子/插排被移动 | 重新估计容器/支撑坐标系，更新所有相对位姿 |
| DYNAMIC_TARGET | 传送带上的目标运动/被放回起点 | 跟踪运动目标，预测到达时间，抓取窗口 |
| HAND_OCCUPANCY | 手占据插口/网口/抓取位 | 让行/等待；手离开后再操作 |

**决策逻辑（chunk 边界）：**

```text
if hand_in_gripper_volume or TTC < 0.2s:
    return SAFE_STOP / HOLD_WAIT
elif type == UNDO_STEP and predicate[step-1] < 0.5:
    rollback_to_earliest_invalid()
    return RE_DO_STEP
elif type in (MOVE_TARGET, REMOVE_OBJECT, MOVE_SUPPORT):
    return RE_LOCALIZE / HOLD_WAIT
elif type == DYNAMIC_TARGET:
    return TRACK_AND_GRASP
else:
    return VLA chunk
```

### 4.4 恢复层：完成栈 + 最小回滚

**完成栈：** 每完成一步，push `{step_id, object_relations, pose, timestamp, predicate_confidence}`。

**最小回滚：** 人撤销/移动后，从栈顶向下找“最早失效”的步骤；只回退到那一步，不整题重来。

```python
def rollback_to_earliest_invalid(predicates):
    for i in range(len(stack)-1, -1, -1):
        if predicates[stack[i].step_id] < 0.5:
            target = stack[i].step_id
            while stack and stack[-1].step_id >= target:
                stack.pop()
            return target
    return current_step  # 没有失效，保持
```

**恢复 primitive：**

| primitive | 语义 | 何时用 |
|---|---|---|
| SAFE_RETREAT | 退到安全位姿，保持/放开夹爪 | 人手进入夹爪体积/路径 |
| HOLD_WAIT | 保持当前位姿与抓取，等待人手离开 | 人拿走/移动目标，暂不可操作 |
| RE_LOCALIZE | 移动头/底座/腕相机，重新检测物体与容器 | 物体被移动/遮挡 |
| RE_GRASP | 打开夹爪，重新接近/抓取 | 物体被放下/滑落 |
| RE_PLACE | 重新对准容器/槽位，放置并验证 | 目标被移动/放置失败 |
| RE_DO_STEP | 用 VLA 重新执行失效步骤 | 人撤销了步骤 |
| ABORT | 时间/安全不允许，停止 | 180s 预算耗尽或人持续阻挡 |

**预算：**

- 每个 hazard 最多 2 次恢复；长程任务（T16/T17/T31）最多 1 次。
- 总时间守卫：180s；预留 20s 给恢复；等待人类的时间计入预算。
- 若恢复次数用尽，回退到 VLA 重规划或 ABORT，保留已完成步骤的部分分（tie-break 用）。

### 4.5 安全层

- **工作区划分**：机器人前方 0–30cm 为“夹爪闭合体积”，人手进入即 STOP；30–60cm 为“减速区”；60cm 外正常。
- **速度限制**：人手在场景内时，EE 速度 ≤0.1 m/s；无人时正常。
- **退路**：任何时刻保留一条向后的无碰撞路径；恢复 primitive 优先选退路。
- **急停**：用户测试时人手持有急停；评测时依赖官方安全协议（未知，保守假设）。
- **不抓人手**：夹爪闭合前检查闭合体积内无手；否则 open + retreat。

### 4.6 运行时：chunk 级状态机与反应延迟

**关键约束：** `get_action` 返回 `(T_a, …)` 的 chunk；评测端按顺序执行，直到下一次调用。因此从“人手出现”到“机器人改变动作”的延迟下界约等于 `T_a/30s`。

| T_a | chunk 时长 @30Hz | 人手 1 m/s 可移动 | 适用 |
|---:|---:|---:|---|
| 4 | 133ms | 13cm | human 轴高反应；推荐 |
| 8 | 267ms | 27cm | 平衡；推荐上限 |
| 16 | 533ms | 53cm | 干净数据/自由空间；human 轴太慢 |
| 32 | 1067ms | 107cm | 不可用于 human 轴 |

**建议：**

- `action_chunk_size = 4–8`；如果推理延迟撑不住，用 8 + 蒸馏/量化。
- `obs_delta_indices` 对头/腕图像堆叠 `[-8,-4,0]` 或 `[-4,0]`，给 human head 运动线索；语言 `[0]`。
- `image_resize` 头相机 240×320，腕相机 240×320 或 480×640；优先保 latency。
- `control_space = ee`；恢复 primitive 用 EE 目标，VLA 也用 EE。
- 在 chunk 内如果 human head 预测 TTC <0.2s，当前 chunk 的剩余动作无法撤回；因此**保守策略**是：只要人手在减速区，就返回“保持/后退”的短 chunk，而不是继续任务 chunk。
- 推理服务：单卡/多卡；目标 p99 <200ms（T_a=4 时 133ms 是硬上限；p99 200ms 意味着会掉帧/延迟，需蒸馏）。如果达不到，T_a=8 + 保守让行。

> 注：评测端是否允许提前调用 `get_action` 未核实；上表按“执行完 chunk 再调用”的保守假设。若允许提前调用，反应会更快，但不要依赖。

### 4.7 运行时伪代码

```python
class COHASM:
    def __init__(self, spec, hazard_table, policy):
        self.spec = spec
        self.hazards = hazard_table
        self.policy = policy
        self.s = 0
        self.stack = []
        self.human = "ABSENT"
        self.recovery = "NOMINAL"
        self.retries = 0
        self.t0 = now()

    def step(self, obs):
        # 1) perception
        h = human_head(obs)           # keypoints, object, type, TTC, conf
        p = predicate_head(obs)       # P(step complete)
        self.update_human_state(h)

        # 2) safety first
        if h.in_gripper_volume or h.ttc < 0.2:
            return self.safe_chunk("STOP")
        if h.in_slow_zone:
            return self.safe_chunk("SLOW")

        # 3) human event -> recovery
        if h.type == "UNDO_STEP" and p[self.s - 1] < 0.5:
            self.rollback_to_earliest_invalid(p)
            self.recovery = "REPAIR"
        elif h.type in ("MOVE_TARGET", "REMOVE_OBJECT", "MOVE_SUPPORT"):
            self.recovery = "REPAIR"
        elif h.type == "DYNAMIC_TARGET":
            self.recovery = "TRACK"

        # 4) recovery
        if self.recovery != "NOMINAL":
            chunk = self.repair(obs, h, p)
            if chunk is not None:
                return chunk

        # 5) nominal task
        if self.s < len(self.spec.steps) and p[self.s] > 0.8:
            self.stack.append(Frame(self.s, obs, p[self.s]))
            self.s += 1
        if self.s >= len(self.spec.steps) and p[-1] > 0.8:
            return self.done_chunk()

        # 6) VLA chunk with phase + hazard context
        return self.policy.act(
            obs,
            phase=self.s,
            hazard=self.hazards.active(self.s, h),
            budget=self.remaining(),
        )

    def repair(self, obs, h, p):
        if self.retries >= self.spec.max_retries:
            return self.abort_chunk()
        self.retries += 1
        primitive = self.select_primitive(h, p)
        return self.execute(primitive, obs)
```

## 5. HUT：人类干扰用户测试数据引擎

### 5.1 为什么必须做用户测试

- 官方 33k 是干净遥操作；没有 human 干扰片段（本轮未发现 human 子集/字段）。
- 公开备注只是示例视频标注，不是评测剧本；不能靠 12 条备注覆盖真实分布。
- 纯合成人手有域差：外观、速度、遮挡、时机、意图都不真实；合成可以补覆盖，不能替代真人。
- HUT 同时产出三样东西：**训练数据、覆盖率报告、HRI 评估**。

### 5.2 参与者与条件

- **参与者**：8–12 名成年人；不要求机器人经验；其中 2–3 名机器人研究者做 pilot。避免全是本团队成员（减少 expert bias）。
- **任务**：优先 5 个“撤销/拿走”任务：T27 StackBowls、T19 ZipUp、T14 PourOutMedicine、T17 OrganizeStationery、T16 FoldTowel；第二批加 T10 PlugCharger、T12 Unlock、T24 ConveyorSorting、T25 StoreCups。
- **条件**（within-subject，拉丁方平衡）：
  - A：**human-only**（机器人不动/不出现），记录自然干扰轨迹；每任务 2 次。
  - B：**robot-only**（无人干扰），基线；用官方数据或现场 2 次。
  - C：**robot + human，CO-HASM ON**；每任务/每脚本 2–3 次。
  - D：**robot + human，CO-HASM OFF（VLA-only）**；每任务/每脚本 2–3 次。
- **时机随机化**：早/中/晚三个时间窗；每个参与者随机分配，避免只测一个相位。
- **脚本**：不给用户逐字剧本，只给“类型 + 目标物体 + 大致时机”；让用户自然执行。这样得到的是分布，不是排练。

### 5.3 协议与样本量

**主实验（推荐）：**

```text
5 tasks × 2 conditions (C/D) × 2 scripts × 2 reps × 10 participants = 400 episodes
```

400 太多；压缩为：

```text
5 tasks × 2 conditions (C/D) × 1 script × 2 reps × 10 participants = 200 episodes
```

每 episode 30–60s；200 × 45s ≈ 2.5h 机器人时间；加准备/重置/休息，约 2–3 周（每天 2–3h）。如果时间紧，先做：

```text
3 tasks (T27/T19/T10) × 2 conditions × 1 script × 2 reps × 8 participants = 96 episodes
```

**辅助实验：**

- human-only 轨迹：2 tasks × 2 scripts × 8 participants × 2 reps = 64 episodes；用于 human head 预训练/校准。
- HRI 问卷：每个参与者结束后填 NASA-TLX、信任、安全感、让行可理解性（5 点 Likert）。
- API user test：5 名队友模拟评测端（随机 obs stacking、网络抖动、reset、token 错误），记录接口失败；这是工程 gate，不是研究主实验。

每 episode 一个 JSON + 4 路视频 + 状态轨迹：

### 5.5 覆盖率矩阵（T27 示例）

| 转移 | 触发 | 期望响应 | 官方示例覆盖？ | HUT 优先级 |
|---|---|---|---|---|
| S0→S0 | 人移动 pink bowl / bowl1 | 等待、重新定位、重试 | human_1（示例） | 中 |
| S1→S1 | 人靠近 bowl2 | 减速/保持抓取 | 否 | 高 |
| S2→S1 | 人拿走 bowl2（undo） | 谓词 1→0，回滚 S1，重做 | human_4（示例） | 高 |
| S2→S2 | 人在运输中拿走 bowl3 | 等待、重新定位、重抓 | 否 | 高 |
| S1/S2→re-localize | 人移动 rack/base | 重估容器坐标系 | 否 | 中 |
| S3→S3 | 人碰倒 stack | 稳定性检查，重堆 | 否 | 高 |

**覆盖率指标：**

```text
coverage = |visited transitions| / |reachable transitions|
hazard_coverage = |visited hazard transitions| / |hazard transitions|
failure_matrix[task][hazard] = recovery success rate
```

**覆盖率驱动的测试选择：**

1. 枚举每任务的 hazard transitions；
2. 用官方示例标注“已知覆盖”；
3. 用 HUT 运行，记录 visited；
4. 选下一个测试：`argmax (1 - covered) × expected_failure_impact`；
5. 失败案例进入训练集；重复直到 coverage ≥80% 或预算耗尽。

### 5.6 HRI 辅助指标

- **NASA-TLX**：用户主观负荷；如果机器人让行太频繁，负荷会升高。
- **信任/安全感/可理解性**：5 点 Likert；用于判断让行策略是否“自然”。
- **客观安全**：人-机最小距离、near-miss（<10cm）、碰撞次数、急停次数。
- **效率**：任务时间、恢复时间、等待时间、重试次数。
- 这些不直接计分，但能指导 HSM 参数（减速距离、等待阈值、重试预算），并形成论文的 HRI 贡献。

### 5.7 伦理与 QA

- 知情同意、可随时退出；视频去脸/模糊；不收集个人身份信息；如果发表，走 IRB/伦理审查。
- 安全协议：用户站在桌子侧面，不进入机器人后方；急停可用；机器人限速；人手进入夹爪体积即停止。
- 数据 QA：10% 双人标注；检查手部关键点、干扰类型、时序、结果；单批拒绝率 >20% 停采并重训标注员。
- 数据许可：自采数据只用于本赛事/研究；不转售、不再分发；与官方格式对齐（LeRobot v3、四路相机、EE base 位姿）。

## 6. 训练配方

### 6.1 模型与辅助头

- **底座**：WLA-1.0-Base（6B，Apache-2.0，24GB 可微调；[S26][S27]）。如果 MolmoAct2/WALL-OSS 权重可用且许可允许，可作为对照/替换；本轮以 WLA 为可复现基线。
- **动作专家**：LoRA rank 64 / alpha 128；chunk 4–8；EE 空间。
- **Step predicate head**：2 层 MLP/轻量 transformer，输入 VLA 视觉 token + proprio + phase embedding；输出每步完成概率。
- **Human-aware head**：手部热图（2D）、物体归属、干扰类型（7 类）、TTC 回归、置信度。
- **单模型合规**：两个 head 都挂在同一 checkpoint 上；HSM 是确定性代码；human detector 的 classical 兜底是传感器预处理，不是任务模型。模型卡写清楚。

### 6.2 数据混合

| 数据 | 用途 | 比例 |
|---|---|---:|
| 官方 33k 干净演示（抽样 8 任务 × 300 条） | 基础技能/谓词 | 60–70% |
| HUT 真实 human 干扰（200–400 episodes） | human head + 恢复 | 20–30% |
| 合成 human overlay/扰动（1k–2k） | 覆盖长尾 | 5–10% |
| 恢复成功/失败片段（从 HUT 挖） | 恢复策略 | 5–10% |
| HABIT（可选，若许可/embodiment 合适） | human-aware 预训练 | 0–10% |

**原则：** 真实 human 数据是主，合成是补；合成不超过 20%，避免域差主导。

### 6.3 损失

```text
L = L_flow
  + λ1 L_step        # 步骤谓词 BCE
  + λ2 L_hand        # 手部热图 MSE
  + λ3 L_disturb     # 干扰类型 CE
  + λ4 L_ttc         # time-to-contact Huber
  + λ5 L_rec         # 恢复动作 BC / 成功分类
  + λ6 L_cons        # 预测与 HSM 状态的一致性
```

起始权重：λ1=0.2, λ2=0.1, λ3=0.1, λ4=0.05, λ5=0.1, λ6=0.05。早停看真实 held-out + human 轴，不看合成成功率。

### 6.4 课程

| 阶段 | 数据 | 目标 | 退出条件 |
|---|---|---|---|
| 0 | 干净 100% | 复现 WLA 基线 | 干净 held-out 不降 |
| 1 | + step 谓词 | 步骤状态稳 | 谓词 F1 +5 |
| 2 | + 合成 human overlay | head 不崩 | 合成 human F1 >0.7 |
| 3 | + 真实 HUT | human head 可用 | 真实 human F1 >0.8 |
| 4 | + 恢复片段 | 回滚/重做可用 | 回放恢复成功 >60% |
| 5 | + 全量/蒸馏 | 延迟达标 | p99 <200ms（T_a=8） |
| 6 | 平台调试 | 真机 human 轴提升 | +10pp 或停 |

### 6.5 算力

- TLE/谓词标注（8 任务 × 300 条）：8×H100 约 3–5 天。
- human head + VLA LoRA：8×H100 约 2–3 周。
- HUT 数据采集：2–3 周（与训练并行）。
- HSM 工程/回放：1–2 人周。
- 最小可运行版（无重训）：classical hand detector + HSM + 官方 WLA 推理；单卡 24GB 可行，先验证“让行/回滚”是否有效。

## 7. 评测协议

### 7.1 离线（每天）

| 指标 | 目标 |
|---|---|
| Step predicate F1 | ≥0.85 |
| Human hand F1 | ≥0.80（真实 HUT） |
| Disturbance type accuracy | ≥0.75 |
| TTC MAE | ≤150ms |
| Recovery success（replay） | ≥60% |
| Hazard coverage | ≥80% |

### 7.2 本地 replay（每周）

- 用 HUT 录制的 episode 做 open-loop replay：观测→HSM→动作选择；不执行真机，只评估“是否选对让行/回滚/重做”。
- 对比：CO-HASM vs VLA-only vs 保守减速。
- 指标：recovery success、time-to-recover、false yield rate（不必要让行）。
- 这是主要的快速迭代回路；比真机便宜 100×。

### 7.3 平台 debug（版本门）

- 任务：T27（undo）、T19（unzip）、T10（pull plug）、T14（re-cap）、T17（reopen）。
- 每次大版本 1 个 slot；判定：human 轴成功 ≥ +10pp 且无干净轴回归。
- **关键未知**：不计分单任务调试是否包含 10 次完整泛化（含 human）？如果只测 1 次干净条件，debug 价值大减；先邮件确认，否则用本地 replay + 盲跑。
- 如果 debug 不含 human，改用 2 次计分跑（W7/W8）做最终验证，并用 HUT 回放做发布门。

### 7.4 计分跑

- W7 中期 1 次，W8 终期 1 次；如果只允许 1 次，留 W8。
- 提交前 4h soak：N 端口并发、状态隔离、健康检查、token、reset、chunk 边界、p99 延迟。
- API 状态机：handshake → ready → act* → reset → act* → …；任何异常进入安全停止；日志脱敏。
- 模型卡：单 checkpoint、辅助头、HSM 代码、classical detector、数据来源、许可、合规开关。

### 7.5 统计

- 320 trials，bootstrap 95% CI；human 轴 64 trials，CI 约 ±11pp（p=0.5 时最宽）；不要用单任务 2 次 human trial 做结论。
- HUT 200 episodes 的 human 轴 CI 约 ±7pp；足以检测 +25pp。
- 排行榜占位数字不用于显著性检验；只用于目标设定。

## 10. 创新点清单（持续迭代）

> 状态：押注=本轮主线；保留=沿用；升级=旧点被改造；降级=保留但不再是主回路；砍=不做。评分 1–10 为“对本赛事的期望价值/可行性”综合。

### I14 CO-HASM：人机共处分层状态机（新增，押注，9/10）

- **动机**：human 轴 20% 权重；官方数据零 human 片段；撤销/移动会破坏已完成步骤，端到端 VLA 没有显式回滚。
- **差异**：不是“更大的 VLA”，而是“任务区×人类区×恢复区×安全区”的 statechart；转移在 chunk 边界；完成栈+最小回滚；解析 primitive 让行/重做。
- **可行性**：HSM 是确定性代码；PhysVLA/CommitFlow/Harness/Recova 都证明相位 FSM/恢复程序有效；无需重训底座也能先跑。
- **资源**：1–2 人周工程；classical hand detector；G1 调试槽。
- **步骤**：S2H → HSM v0 → classical detector → 回放 → 真机 debug → 迭代。
- **风险**：谓词噪声/检测误判 → 置信度回退；HSM 脆 → 只硬编码高价值任务，其余用 VLA。

### I15 HUT：人类干扰用户测试数据引擎（新增，押注，9/10）

- **动机**：官方 33k 干净数据不产生 human-aware 行为（HABIT）；公开备注不是剧本；合成有域差。
- **差异**：不是“采更多干净演示”，而是“用真人采 human 轴 + 覆盖率驱动 + HRI 评估”；产出训练数据、失败矩阵、论文。
- **可行性**：G1 实验室可做；200 episodes 2–3 周；LeRobot 格式对齐。
- **资源**：G1+Dex1；8–12 用户；四路相机；标注；伦理审查。
- **步骤**：招募 → pilot → 主实验 → QA → 训练 → 覆盖率报告。
- **风险**：外部数据合规 → 默认只做验证；用户安全 → 限速/急停/侧站；样本偏差 → 多样用户/时机。

### I16 S2H：Score-Step-to-HSM 编译器（新增，支撑，8/10）

- **动机**：32 任务手工写状态机不现实；官方 score_steps 是现成的任务骨架。
- **差异**：把评分 rubric 编译成控制器；步骤→技能→谓词→hazard→YAML；不是 LLM 自由规划。
- **可行性**：32 任务一次编译；谓词用演示分布拟合；人工复核 10%。
- **资源**：1 人周 + LLM API/本地模型；演示数据。
- **步骤**：技能本体 → 步骤解析 → 谓词归纳 → hazard 标注 → YAML → 回放验证。
- **风险**：步骤文本歧义 → 人工复核；谓词不可观测 → 用视觉/几何代理；过拟合官方步骤 → 保留 VLA 兜底。

### I17 完成栈 + 最小回滚（新增，支撑，8/10）

- **动机**：人撤销一个步骤后，整题重来浪费 180s；最小回滚只重做失效步。
- **差异**：不是“失败重试”，而是“用谓词失效定位最早坏点”；与 SSG/谓词头天然对齐。
- **可行性**：栈+谓词即可；无需新数据。
- **资源**：CPU；1 人周。
- **步骤**：完成栈 → 失效检测 → 回滚目标 → 恢复 primitive → 预算。
- **风险**：谓词误判导致错误回滚 → 双阈值/置信度；回滚后场景变化 → 重新定位。

### I18 Human-aware head（新增，支撑，7.5/10）

- **动机**：classical 手检测在遮挡/快速运动下不稳；端到端 head 可利用 VLA 语义。
- **差异**：不是独立模型，而是同一 checkpoint 的辅助头；输出手/物/类型/TTC。
- **可行性**：VLA 视觉 token + 轻量 head；HUT 数据训练。
- **资源**：8×H100 数天；标注。
- **步骤**：热图/类型/TTC 标签 → 辅助损失 → 蒸馏 → 延迟测试。
- **风险**：单模型审计 → 同 checkpoint；数据不足 → 合成+classical 融合；延迟 → 轻量头。

### I19 覆盖率驱动的人类用户测试（新增，方法，8/10）

- **动机**：随机用户测试覆盖不了长尾；状态机给了可枚举的转移目标。
- **差异**：把软件测试的 coverage-guided fuzzing 搬到人-机共处；用 hazard transition 作为覆盖目标。
- **可行性**：HSM 转移可枚举；HUT 可记录 visited；选择策略简单。
- **资源**：HSM + HUT 数据；1 人周分析。
- **步骤**：枚举 → 记录 → 覆盖率 → 选下一个 → 失败入库 → 迭代。
- **风险**：覆盖≠成功 → 同时看 failure matrix；转移爆炸 → 按影响排序。

### I20 Chunk 级反应约束（新增，接口，7/10）

- **动机**：human 轴要求 <200ms 反应；chunk 开环执行，T_a 决定反应下界。
- **差异**：把 `action_chunk_size` 当 human 轴的一等设计变量，而不是纯吞吐参数。
- **可行性**：README 明确 chunk 语义；T_a=4–8 可配；蒸馏/量化可压延迟。
- **资源**：推理优化；压测。
- **步骤**：测 T_a/延迟/反应 → 选 4–8 → 安全 chunk → 压测。
- **风险**：推理撑不住 → 蒸馏；评测端提前调用未知 → 保守假设。

### I21 API 状态机 + 用户测试 harness（新增，工程，5/10）

- **动机**：远程评测的失败常来自 handshake/reset/token/chunk/网络，而不是模型。
- **差异**：把提交服务当状态机测试；队友模拟评测端做“用户测试”。
- **可行性**：README 明确接口；可本地 mock。
- **资源**：1 人周；5 名队友。
- **步骤**：状态图 → mock evaluator → 抖动/错误注入 → soak。
- **风险**：过度工程 → 只做 release gate；真实评测行为未知 → 保守兼容。

## 13. 开放问题

1. **不计分单任务调试是否包含 10 次完整泛化（含 2 次 human）？** 如果只测 1 次干净条件，human 轴的平台验证就不成立；这是本轮最关键的问题，先发邮件确认。
2. **human_1/human_4 是示例视频标注还是评测剧本？** 本轮高置信推断为示例视频；需要官方确认。
3. **评测端是执行完整 action chunk 再调用，还是可以提前调用？** 这决定 human 轴的反应下界；按保守假设设计 T_a=4–8。
4. **人为干扰如何实施？** 同一操作员？固定脚本？随机时机？干扰幅度/速度范围？是否允许机器人等待/暂停？
5. **外部自采 human 数据能否用于训练？** 手册摘录未写；默认只做验证，邮件确认后再开。
6. **辅助头/classical detector 是否算“多模型”？** 规则说“不得混合多个模型做不同任务”；我们倾向同 checkpoint + 模型卡披露；需要官方解释。
7. **每任务 180s 是否包含人类等待/恢复？** 应该是；如果是，恢复预算要更严。
8. **10 次运行的顺序是否固定/随机？** 示例备注的编号是否与试次顺序有关？未核实。
9. **榜单是否提供轴级结果？** 目前只看到总体/任务级；轴级结果会极大帮助诊断。
10. **真实榜单何时发布？** 当前 `leaderboard_data.json` 仍是占位；真实基线未知。
