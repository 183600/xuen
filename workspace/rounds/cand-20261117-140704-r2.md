# 第 12 轮（灵感循环第 3 轮；本轮灵感：「模仿学习」×「决策规划」）

> **基线**：第 11 轮 MetricVoiceGauge-NCD-H（定义 554–570；引理 96–103；实验 E589–E606；IP-363–366）。
> 本轮纪律：**示范只产契约 + 假设必须可反驳 + 规划必须显式买信息**。不推倒 v11：HAS/HCC/HATD/HDT、MetricVoiceGauge 九不变式、NGE/DSL/CC/CWM/CAE/NCP、AC/MW/ID、DA/SPR/Cal 全部保留；本轮只把“人类示范”接入为可审计契约，把“决策规划”升级为假设感知的风险约束 POMDP。模仿旁路是**单点可关断**的：任一组件失效即整体关闭，严格等价退回 v11，再沿 v11 十三级链退回 v10/v9/v8/v7/v6。

## 0. 直觉与动机

### 0.1 v11 真正遗留的两个缺口

v11 已经把“规范、接触、因果、谐波”四类约束接进同一个块级决策闭环，但它仍默认两件事：

1. **候选生成与人类经验脱节**：HATD 每次在新任务上从零在谐波状态空间做 A*/MCTS，CWM/HDT 对每个候选做反事实 rollout。新家庭、新物体、新接触模式意味着几乎从零搜索；而人类示范里恰好含有大量“什么时候该用哪种抓取/推拉/交接”的经验，却没有被安全地复用。
2. **规划只对“世界”建模，不对“自己的假设”建模**：v11 的证书覆盖物理、接触、谐波、规范，却不覆盖“我正在使用的这个行为，其成立条件此刻是否仍然成立”。当 v11 使用人类示范或学习到的选项时，规划器没有显式的假设信念、没有“先检验再执行”的决策，也没有“何时该向人求助”的决策。证书是对象级的，行为假设是认识论级的，两者之间缺一个接口。

两个灵感词正好击中这两个缺口：**模仿学习**可以把人类经验变成可复用的行为候选，**决策规划**可以把“相信、检验、求助、放弃”变成同一个风险预算下的决策。但二者直接相加会产生一个比 v11 更危险的东西：**一个来自示范、看起来很自然、置信度很高的行为，被当作策略权威直接执行，而它的成立条件从未被任何证书检查过**。本轮的全部设计都是为了避免这个组合。

### 0.2 灵感 1（模仿学习 → 示范契约，而不是策略克隆）

直觉：模仿学习最诱人的叙事是“让人示范一遍，机器人照着做”。但在 v11 这种已带四重安全证书的系统里，把人示范的动作直接克隆成策略会破坏证书链：

- 示范置信度来自数据似然，不是来自物理/接触/谐波/规范可行性；
- 人类示范含有大量**因果混淆与捷径**：人总是从红色杯子那一侧抓，可能只是因为当时只有红色杯子；人先抬腕再前伸，可能只是因为桌面高度；这些相关不等于因果；
- 行为克隆的误差在时间上相关，闭环执行会把小误差放大成分布外状态；
- 示范数据无法告诉我们“这个行为在什么条件下会失效”，因为人只展示了成功的那一支。

核心创新：**示范契约编译器（Demonstration Contract Compiler, DCC）**。DCC 不从示范中抽取“动作策略”，而抽取**契约（contract）**：一个带显式假设集、监视器、可反驳检验、后置条件、失败回退与来源审计的行为选项。直觉上，契约回答的不是“人怎么动”，而是：

> **“人在什么可观测条件下这样做，且这些条件一旦被破坏，我如何知道、如何检验、如何退回？”**

DCC 只允许把示范编译成 **v11 已有 HAS 原语的宏序列**或参数化家族；若示范中的动作无法用 v11 DSL 表达，则拒绝该段示范，而不是新增未认证原语。这样模仿只能重组合法能力，不能扩大底层可执行集。

### 0.3 灵感 2（决策规划 → 假设感知的“执行 / 检验 / 求助”）

直觉：v11 的规划器本质上是一个“证书过滤器 + 反事实评分器”：它从候选块中删掉不安全的，再按任务价值排序。它没有把**信息**当作动作。真实决策中，最危险的不是“选错动作”，而是“在一个自己不确定的假设上直接执行”。当契约带有假设集时，规划器必须回答三个问题：

1. 现在是否所有假设都成立？如果成立，执行契约；
2. 如果有假设不确定，做哪个检验最能降低风险/提高价值？检验本身是否安全、是否值得？
3. 如果检验也解决不了，是否向人求助，还是直接退回 v11 的保守方案？

核心创新：**假设感知盾式规划器（Assumption-Aware Shielded Planner, AASP）**。AASP 把决策写成带安全约束的 POMDP，状态显式包含**假设信念** `b_A`、契约上下文、风险预算与信息预算；动作集扩展为 `{执行契约, 运行检验, 向人求助, 回退}`。它用**信息价值（VOI）**比较“现在执行”与“先花一点代价把假设弄清楚”，并用 v11 证书作为**盾**：任何检验、求助、执行都必须是 v11 证书允许的；若没有可行动作，立即回退。**规划不只选动作，还选信息。**

### 0.4 灵感 3（模仿 × 规划 → 干预触发的契约修复闭环）

直觉：模仿与规划相加后，最容易犯的错是“人类纠正一次，就把纠正当成新示范再克隆一遍”。这会把局部纠正过拟合、把人的偶然偏好当成规律，并可能悄悄削弱原契约的失败回退。更合理的做法是把人类干预当作**证据**，只修复契约的“认识论部分”：

- 若干预指出“你漏掉了一个条件”，就给契约增加假设、增加监视器或检验；
- 若干预指出“你的监视器误报了”，就重校准监视器阈值或分裂上下文；
- 若干预指出“你的检验太弱”，就替换成更有区分力的检验；
- 若干预指出“这个分布已经变了”，就收缩支持集或增加上下文，并重新走契约认证。

核心创新：**主动契约修复与增广（Active Contract Repair & Augmentation, ACRA）**。ACRA 把干预事件、v11 的 CWM/HDT 反事实 rollout、以及扰动生成的近失负例，统一用于训练监视器/检验器、修复假设集与支持集；但所有反事实标签都带 `prov=sim`，只能训练，不能认证。修复只能**加强**契约，不能删除回退、不能放宽 v11 证书、不能把统计假设变成硬保证。

### 0.5 三者如何统一

把决策写成**契约化模仿—规划闭环（Contractual Imitation–Planning Loop, CIPL）**：

```
人类示范 ──DCC──> 契约候选 κ（假设集 A、监视器 Mon、检验 Test、回退 Fallback、来源 prov）
                         │
                         ▼
                    COC 契约认证（只删：不可监视/不可反驳/回退不可达/无检测安全裕度 ⇒ 拒绝）
                         │
                         ▼
       AASP 假设感知规划（执行 / 检验 / 求助 / 回退；风险预算 + VOI + 盾）
                         │
                         ▼
             v11 四重证书 + 契约监视器 + 块守卫（只执行、只截断、只回退）
                         │
                         ▼
        干预事件 / 近失 / 反事实增广 ──ACRA──> 契约修复（只加强） ──> 重新 COC
```

**模仿回答“人类怎么做”，契约回答“何时可以相信”，规划回答“下一步是执行、检验还是求助”，修复回答“错了以后怎样变得更可检验”。** 四者共享 v11 的 `S*、ζ_h、CWM、HCC`，因此不是四个补丁，而是一个**示范—契约—规划—修复**闭环。

### 0.6 为什么不是这些“显然的解法”

| 显然解法 | 为什么不够 |
|---|---|
| 端到端行为克隆一个动作策略 | 置信度不可证书化；因果混淆与捷径不可见；失效时无法逐位退回 v11 |
| 模仿策略 + v11 证书过滤器 | 证书只检查物理/接触/谐波/规范，不检查“行为假设是否成立”；过滤器会放行“物理安全但语义错误”的契约 |
| 固定一张人工假设清单 | 假设随任务/物体/人/磨损漂移；清单外的新失效无法被发现；不可反驳 |
| DAgger 式无差别收集纠正 | 纠正发生在分布外状态，样本效率低；无安全过滤的探索可能不可逆；纠正会污染安全回退 |
| 只用仿真反事实增广 | CWM/HDT 与监视器共享仿真偏差，会自我确认；仿真标签不能当证书 |
| 对每个假设都做穷举检验 | 检验有成本、可能改变状态、可能不可逆；需要 VOI 与风险预算，而不是“全测一遍” |
| 让规划器直接在原始动作空间做 POMDP | 维度爆炸、证书难以逐动作验证；应先规划契约选项，再由 v11 守卫执行原语 |

## 1. 研究问题（轮次升级版）

- **Q1（契约可辨识性）**：如何从有限、含噪、含因果混淆的人类示范中，抽出“可监视、可反驳、可回退”的假设集，使契约在支持集内可靠、在支持集外能被检测，而不是学到示范中的捷径？
- **Q2（契约准入与检测安全）**：如何认证一个契约的监视器误报/漏报、检测延迟与回退可达性，使得“假设失效但尚未被检测到”的窗口内系统仍处于 v11 安全集？检测延迟与不可逆风险之间是否存在可计算的安全裕度？
- **Q3（假设感知规划最优性）**：在风险预算与信息预算下，如何选择执行/检验/求助/回退，使任务收益最大？VOI 计算在契约数量、假设维度、检验组合下是否可近似？贪心检验选择何时有 `1−1/e` 类保证？
- **Q4（干预修复的收敛与不弱化）**：如何用稀疏、带偏、可能互相冲突的人类干预修复契约，保证修复只加强不弱化，并给出样本复杂度与分布偏移下的收敛界？
- **Q5（兼容性与预算）**：契约层是否可能因过度保守而清空可行集？如何保证 v12 的物理执行集始终是 v11 的子集、模仿旁路关闭时逐位等价 v11、且总决策 p99 仍不超过 22ms？

## 2. 设计原则（在 P16–P18 基础上新增 P19–P23）

**P19 契约优先于策略律（Contract over Policy）**
模仿学习的输出必须是**契约**，不得直接成为执行策略。契约 = 合法的 v11 原语序列 + 显式假设集 + 监视器 + 可反驳检验 + 后置条件 + 失败回退 + 来源审计。没有契约的示范片段只能作为离线研究数据，不能进入在线执行。

**P20 假设可反驳律（Falsifiable Assumption）**
每个统计假设必须至少配一个监视器和一个安全检验；每个关键假设必须是硬不变量或可被有限步检验区分。不可监视、不可检验、不可回退的假设 ⇒ 契约不可准入。禁止“相信但无法验证”的假设进入执行链。

**P21 规划—信息一体律（Planning–Information Unity）**
规划动作集必须显式包含“检验”和“求助”，并把它们与执行、回退放在同一个风险/成本预算下比较。禁止“先相信再执行、出事再解释”的开环契约使用方式；任何未决假设都必须由 `执行 / 检验 / 求助 / 回退` 四选一显式处理。

**P22 单点可关断律（Single-Point Bypass Shutoff）**
模仿旁路是一个整体可关断的可选增强，而不是四个可独立拼接的补丁：DCC/COC/AASP/ACRA 任一不可用或自检失败 ⇒ 关闭整条旁路 ⇒ 严格等价 v11。原因：部分可用的模仿层会产生“有契约、但契约没有被完整认证/规划/修复”的灰色行为，比完全不用更危险。

**P23 反事实只训不信律（Counterfactual Training-Only）**
由 CWM/HDT 生成的反事实标签只能用于训练监视器、检验器、契约提议与测试用例，不能作为证书、不能直接准入契约、不能替代实机标定。所有仿真标签必须带 `prov=sim`，并通过实机校准的覆盖检验后才可影响契约排序。

## 3. 与基线的接口（如何退化）

- **模仿旁路关闭** ⇒ `K_IL=∅`、AASP 退回 v11 NCP、无检验/求助、ACRA 冻结；主闭环调用序列与 v11 逐位一致，**严格等价 v11**；
- **DCC 失效** ⇒ 不产生新契约，旁路关闭，**等价 v11**；
- **COC 失效** ⇒ 所有契约不可准入，旁路关闭，**等价 v11**；
- **AASP 失效** ⇒ 契约无法被假设感知地执行，旁路关闭，**等价 v11**；
- **ACRA 失效** ⇒ 契约集与监视器冻结，旁路关闭，**等价 v11**；
- **v11 链**：再沿 v11 十三级链退回 v10/v9/v8/v7/v6；
- **安全继承**：契约的底层原语、检验动作、求助动作、回退动作全部必须是 v11 证书允许的；DCC 只能提议、COC 只能删除、AASP 只能选择、ACRA 只能修复元数据。物理/接触/谐波/规范四重证书不被任何模仿组件放宽（引理 106、112）。

## 4. 预期贡献

1. **示范契约化**：把人类示范从“动作克隆”提升为“带假设、监视器、检验、回退与审计的契约”，正面处理模仿学习的因果混淆、捷径、协变量偏移与不可验证置信度；
2. **假设感知的风险约束规划**：把“执行/检验/求助/回退”统一进带安全盾的 POMDP，用 VOI 与储备预算解决“何时相信、何时买信息”的决策问题，使规划从证书过滤升级为认识论决策；
3. **主动契约修复**：用干预、近失与反事实增广修复契约，且修复只加强不弱化，给出样本复杂度与不弱化条件；
4. **向后兼容的 v12 单点旁路**：证明物理执行集不超出 v11、旁路关闭逐位等价 v11、预算仍满足 p99 ≤22ms；实验 E625–E644 覆盖契约抽取、监视器校准、检验选择、安全继承、因果混淆压力测试与端到端收益。

## 5. 本轮最大风险

**一句话**：契约抽取可能漏掉一个连人类示范者自己都未意识到的关键假设，监视器在分布外仍报 `hold`，规划器据此选择“执行”而不是“检验”，系统就在“有契约、有证书”的表象下执行了未被任何证书覆盖的行为——**自信地持有一份漏掉关键假设的契约**。

- Level-2：HDT 失效 ⇒ CWM 用定值谐波模型、HATD 用启发式分解，**等价 v10 推理路径**；
- Level-3：HATD 失效 ⇒ 退回 v10 NCP 直接采样，**等价 v10 规划路径**；
- Level-4：HAS/HCC 失效 ⇒ 注入谐波中立元（θ_flex≡0、τ_h≡τ_cmd、k_h≡∞、证书退化为 v10 Ĉ_contact），**等价 v10 灵巧路径**；
- Level-5：CWM/CAE 失效 ⇒ 预测退回 v9 黑箱 F̂、归因退回相关消融 c_m，**等价 v9 推理路径**；
- Level-6：DSL/CC 失效 ⇒ 技能集退回 v9 低维原语，接触证书退化为 γ_grasp，**等价 v9 操作路径**；
- Level-7：NGE 失效 ⇒ 注入 allow-all 规范中立元，**等价 v9 行为**；
- Level-8：AC 失效 ⇒ K_eff←1，逐步执行，**等价 v8 决策粒度**；
- Level-9：MW 失效 ⇒ 切换 v8 手写网关，**等价 v8 集成方式**；
- Level-10：ID 失效 ⇒ 全模块 active、归因冻结，**等价 v8**；
- Level-11：v8 的 DA/SPR/Cal 任一失效 ⇒ 中立元注入，**等价 v7**；
- Level-12：全失效 ⇒ 完整退回 v7，再退回 v6。

**为什么是单点旁路而不是四个独立端口。** v11 的四个新组件作用于互不相交的执行端口；v12 的模仿组件作用于同一个认识论对象——契约。若允许“DCC 可用但 COC 失效”或“AASP 可用但 ACRA 失效”的部分组合，就会出现“契约被提议但未被完整认证/规划/修复”的灰色行为，其风险高于完全不用模仿。因此 v12 的部署契约是：**任一子组件不可用 ⇒ 整条旁路关闭**。局部中立元仅用于消融实验，不用于部署。

**定义 571（示范契约 Demonstration Contract）** 一个契约是在 v11 灵巧技能之上、带显式认识论条件的行为选项：
```
κ = ( β, A, Mon, Test, post, fallback, S, ε_IL, δ_IL, prov )
β = (π_h^{1:K})                          # 必须全部是 v11 DSL 中的 HAS 原语/参数化家族
A = {a_1,...,a_m},  a_i : H → {0,1}      # 可观测历史上的假设谓词
Mon = {m_1,...,m_m}, m_i : H → {hold,violate,unknown}
Test = {τ_1,...,τ_m}                     # 每个统计假设对应一个 v11 认证的检验
post                                     # v11 认证的后置条件
fallback                                 # v11 认证的回退/中止方案
S                                        # 示范支持集（跨域不变特征 + 任务上下文）
ε_IL, δ_IL                               # 示范模仿误差与置信度（只用于排序，不用于安全断言）
prov                                     # 来源审计：示范 ID、操作者、授权、环境、变换、修复日志
```
契约的语义是“**若 A 成立且 v11 证书成立，则 β 可在支持集 S 内实现 post；否则在检测延迟内回退**”。契约不是策略，不能脱离 `A ∧ v11 证书 ∧ 监视器` 直接执行。

**定义 572（认证监视器 Certified Monitor）** 监视器 m 对假设 a 是 `(α,β,d)`-认证的，若：
```
(健全性)   m(h)=violate ⇒ ¬a(h)                         # 误报率 ≤ β（硬不变量时 β=0）
(漏报界)   P(m(h)=hold | ¬a(h)) ≤ α                     # 在标定分布上
(检测延迟) 若 ¬a 从某时刻起持续成立，则 m 在 d 步内输出 violate，概率 ≥ 1−α
(未知安全) m(h)=unknown 时禁止执行依赖 a 的基动作
```
关键假设（力闭合、无滑移、谐波屈服、规范硬约束）必须使用硬不变量监视器，`α=0`；统计假设使用保形/校准监视器，`α>0` 且计入风险预算。

**定义 573（契约准入 Admissible Contract）** 契约 κ 可准入当且仅当：
```
(C1 基座认证) β 的每个 HAS 原语与 post 均通过 v11 物理/接触/谐波/规范四重证书；
(C2 假设可监视) 每个 a_i 有 (α_i,β_i,d_i)-认证监视器；
(C3 检测安全裕度) 若 a_i 失效，系统在 d_i + t_fb 步内仍处于 v11 安全集，
                  其中 t_fb 为回退执行时间；否则该契约不可准入；
(C4 假设可反驳) 每个统计 a_i 有 v11 认证的检验 τ_i，且 IG(τ_i) ≥ ι_min 或 τ_i 是直接见证检验；
(C5 回退可达) 存在 v11 认证的 fallback，且从契约执行管内的任意可达状态可在 t_fb 内进入 fallback；
(C6 覆盖与来源) 示范支持覆盖 cov(κ) ≥ c_min，且 prov 完整、可审计、无测试集泄漏；
(C7 不弱化) 契约不删除、不放宽任何 v11 硬证书；post 蕴含 v11 任务进度谓词。
```
`Adm(κ) ⇔ C1∧...∧C7`。COC 只做这个判定；任何一条失败即拒绝，不做“降级放行”。

**定义 574（契约的守卫执行 Guarded Contract Execution）** 在历史 h 上，契约 κ 的基动作可执行当且仅当：
```
Exec(κ,h) ⇔ Adm(κ) ∧ (∀i: m_i(h)=hold) ∧ Cert_v11(h) ∧ BudgetOK(h) ∧ h∈S
```
若存在 `m_i(h)=unknown` 或 `violate`，则**不执行任何依赖 a_i 的基动作**；AASP 必须在决策截止期 `T_dec` 内选择检验/求助/回退。超过 `T_dec` 仍未知 ⇒ 强制 fallback。契约回退点集 `P^κ` 是满足“从该点起存在 v11 认证 fallback 且检测安全裕度成立”的历史点；执行要求 `P^nav ∪ P^c ∪ P^h ∪ P^κ ≠ ∅`。

**定义 575（契约化规划 Contractual Planning）** 把决策写成带安全约束的 POMDP：
```
M_κ = ( X, A, T, O, R, C, δ_safe, B )
X = S_phys × Δ(A) × K_ctx × B_risk × B_cost
A = { exec(κ), test(τ), ask(q), fallback }
T: X×A → Δ(X),  O: X×A → Δ(O),  R = task_progress − λ_c·cost − λ_r·risk
```
策略 π 求解：
```
max_π  E_π[ Σ_t γ^t R_t ]
s.t.   P_π(catastrophe) ≤ δ_safe,   E_π[cost] ≤ B_exec + B_reserve,
       B_exec 与 B_reserve 分离，π 不得消耗 B_reserve
```
其中 `b_A` 通过监视器观测与检验结果做贝叶斯更新；`ask` 是**无物理运动**的信息动作（只请求人类反馈/确认），物理接管走 v11 的安全模式。AASP 用盾式 POMCP / 信念空间 A* 求解，动作必须先通过盾 `Sh(b)`。

**定义 576（可反驳检验与信息价值 Falsification Test & VOI）** 对检验 τ：
```
IG(τ|b)  = H(b_A) − E_{o~P(o|b,τ)}[ H(b_A') ]                  # 信息增益
VOI(τ|b) = E_{o}[ V^*(b') − V^*(b) ] − c_τ − λ_r·ΔRisk(τ)      # 信息价值
```
τ 可被 AASP 选择当且仅当：τ 是 v11 认证的、状态变化可逆或可安全回退、`ΔRisk(τ)` 在当前风险预算内、且 `VOI(τ|b) ≥ 0`。禁止“为了信息而做不可逆动作”。

**定义 577（决策模式算子 Decision Mode Operator）** 在每个决策 epoch：
```
if ∃κ: Exec(κ,h) ∧ Q_exec(κ,b) ≥ max(Q_test(b), Q_ask(b)) + margin:
    mode = exec(κ)
elif ∃τ: VOI(τ|b) > 0 ∧ τ admissible:
    mode = test(τ)
elif VOI(ask|b) > max(VOI(test), 0) ∧ intervention_budget > 0:
    mode = ask
else:
    mode = fallback / replan_v11
```
`Q_exec/Q_test/Q_ask` 均为约束后的价值（已扣风险/成本）；`margin` 防止在信息价值接近时反复横跳。该算子保证“未决假设不会被静默执行”。

**定义 578（干预事件与契约修复 Intervention Event & Contract Repair）** 干预事件
```
ι = ( h, κ, i, type, u )
type ∈ { missing_assumption, monitor_false_negative, monitor_false_positive,
         test_weak, support_shift, policy_error }
```
修复算子 `R_ι` 只允许以下加强型更新：
```
missing_assumption      → 增加假设 a'、监视器 m'、检验 τ'；若无监视器/检验 ⇒ 契约不可准入；
monitor_false_negative  → 收紧阈值、分裂上下文、增加独立证据；重新认证 (α,β,d)；
monitor_false_positive  → 放宽阈值或增加上下文条件，但不得降低 α 的安全上界；
test_weak               → 替换/增加更高 IG 的检验，且新检验必须 v11 认证；
support_shift           → 收缩 S 或增加任务/物体上下文，并重新计算 cov(κ)；
policy_error            → 更新 β 的参数，但必须重新通过 C1 四重证书。
```
**禁止**：删除 fallback、放宽 C3 检测安全裕度、降低 C1 证书、把统计假设改成硬保证、用仿真标签替代实机标定。若修复会导致上述任一弱化，则拒绝修复并将契约标记为不可准入。

**定义 579（反事实契约增广 Counterfactual Contract Augmentation）** 由 v11 CWM/HDT 在域随机化分布上生成
```
A_cf = { (s, a, y, prov=sim, ω) }
y ∈ {hold, violate, unknown}     # 由仿真中的假设求值给出
ω = 重要性权重 / 仿真可信度
```
`A_cf` 只用于：(i) 训练监视器与检验选择器；(ii) 生成近失负例与测试用例；(iii) 提议新的假设/上下文。**不用于**：契约准入、证书签发、安全断言。实机标定集上若 `|P_real(y|s) − P_sim(y|s)| > ε_cf`，则对应仿真样本权重降为 0，相关监视器/检验退回实机数据版本。

**定义 580（契约覆盖 Contract Coverage）** 对示范分布 D_demo：
```
cov(κ) = P_{h~D_demo}[ h∈S ∧ ∀i: m_i 有定义 ∧ τ_i 可安全执行 ]
cov_mode(κ,o) = 同上，条件于接触模式 o
```
准入要求 `cov(κ) ≥ c_min` 且任务相关接触模式的 `cov_mode ≥ c_mode`。覆盖不足不是“再克隆多一点”能解决的，必须收缩支持集或拒绝契约。

**定义 581（契约组合 Contract Composition）** 两个契约可组合 `κ = κ1 ∘ κ2` 当且仅当：
```
post_1 ⇒ pre_2  或  存在交接监视器 m_12 使 post_1 ∧ m_12 ⇒ pre_2；
κ1、κ2 均可准入；组合不形成 fallback 环；组合的 prov 可拼接。
```
组合契约的回退是“当前活跃子契约的回退”；若子契约交接失败，回退到最近一个满足 P^κ 的交接点。组合只能减少可执行轨迹，不能放宽任一子契约的证书。

**定义 582（中立元与单点旁路 Neutral Element & Single-Point Bypass）** v12 的部署中立元是整条模仿旁路：
```
v12^⊥: K_IL = ∅;  AASP = v11 NCP;  无 test/ask;  ACRA 冻结;  主闭环调用序列 = v11
```
局部中立元仅用于消融：
```
DCC^⊥  ⇒ K_IL=∅
COC^⊥  ⇒ ∀κ: ¬Adm(κ)
AASP^⊥ ⇒ 无 exec/test/ask，仅 v11 NCP
ACRA^⊥ ⇒ 契约与监视器冻结（不再修复/增广）
```
部署时任一局部中立元触发 `v12^⊥`；因此不存在“半条模仿旁路”的部署状态。

**定义 583（契约—证书合取 Contract–Certificate Conjunction）** 执行安全谓词：
```
SafeExec(κ,h) = Adm(κ) ∧ (∀i: m_i(h)=hold) ∧ Cert_v11(h)
                ∧ h∈S ∧ BudgetOK(h) ∧ P^κ(h) ≠ ∅
```
`Cert_v11` 是 v11 的物理/接触/谐波/规范四重证书；契约不能替代、不能放宽、不能绕过其中任何一个。若 `SafeExec` 为假，唯一允许的动作是检验/求助/回退，而不是“降速执行”。

**定义 584（盾式契约规划 Shielded Contract Planning）** 盾定义为
```
Sh(b) = { a∈A | a=v11 认证动作 ∧
          (a=exec(κ) ⇒ Exec(κ,h)) ∧
          (a=test(τ) ⇒ τ admissible ∧ VOI(τ|b)≥0) ∧
          (a=ask(q) ⇒ intervention_budget>0) ∧
          (a=fallback ⇒ fallback v11 认证 ∧ P^κ≠∅) }
```
AASP 只在 `Sh(b)` 上搜索；`Sh(b)=∅` ⇒ 立即执行 v11 认证 fallback。盾是“动作级”的，不是“策略级”的：即使规划器价值估计错误，也不能选到未认证动作。

**定义 585（契约来源与审计 Contract Provenance & Audit）** `prov` 至少包含：
```
(示范 ID 列表, 操作者/授权, 采集环境与时间, 传感器与标定版本,
 数据变换与增广链, sim/real 标记, 每次修复的事件 ID 与前后哈希,
 训练/验证/测试任务与物体的分层记录)
```
COC 要求 prov 完整、可追溯到原始示范、且测试任务/物体未出现在示范或反事实增广中；否则契约不可准入（防止数据泄漏与“背答案”）。

## 2. 形式化定义（要点与升级）

**升级定义 557（谐波感知任务分解，v12）** HATD 的输出段 `seg` 增加一个可选字段 `κ`：若该段使用人类示范，则必须携带通过 COC 的契约；否则 `κ=⊥`，退化为 v11 段。HATD 的候选集变为 `S_v11 ∪ K_IL`，但 `K_IL` 只增加候选，不改变段的 v11 证书要求。

**升级定义 560（v11 中立元表，v12）** v11 的 HAS/HCC/HATD/HDT 中立元保持不变；v12 在它们之前增加一个**旁路级中立元** `v12^⊥`。`v12^⊥` 注入后，所有 v12 新函数变为恒等/空操作，主闭环回到 v11 调用序列。

**升级定义 534'（三语义中止点，v12）** 中止点集扩展为
```
P_t = P_t^nav ∪ P_t^c ∪ P_t^h ∪ P_t^κ
```
契约段可执行的必要条件增加 `P_t^κ ≠ ∅`：从当前点起存在 v11 认证回退，且回退在监视器检测延迟 + t_fb 内仍处于 v11 安全集。若 `P_t^κ=∅`，AASP 不得选择该契约，HATD 必须重新分段。

**升级定义 531（软硬约束衔接，v12）** M₀ 硬检查增加：
- 契约未准入却被执行 ⇒ M₀ 硬违规；
- 监视器 `unknown` 超过 `T_dec` 仍执行 ⇒ M₀ 硬违规；
- 契约回退被删除/弱化 ⇒ M₀ 硬违规；
- 检验动作未通过 v11 证书 ⇒ M₀ 硬违规。
物理/接触/谐波/规范原有 M₀ 判据不因契约层存在而放宽。

**升级定义 547（接触证书，v12）** `Ĉ_joint = Ĉ_contact ∧ Ĉ_h ∧ Ĉ_κ`，其中 `Ĉ_κ` 是契约准入证书 `(Adm, monitor certificates, coverage, fallback)`。三者合取有效才可执行；`Ĉ_κ` 只能删候选，不能替代前两者。

## 3. 关键算法骨架

```python
# IP-367 DemonstrationContractCompiler
class DemonstrationContractCompiler:
    def __init__(self, dsl_v11, invariant_features, certifier_v11, cwm, provenance):
        self.dsl = dsl_v11
        self.S_star = invariant_features          # v11 跨域不变父集 S*
        self.cert = certifier_v11
        self.cwm = cwm
        self.prov = provenance

    def compile(self, demos, task_ctx):
        # 1) 按接触模式切段；只匹配 v11 已有 HAS 原语，不新增底层原语
        segments = segment_by_contact_mode(demos)
        contracts = []
        for seg in segments:
            beta = self.dsl.match_skill_macro(seg, allowed=self.cert.certified_skills())
            if beta is None:
                continue                           # 无法用 v11 DSL 表达 ⇒ 拒绝，不新增原语
            # 2) 对比成功/失败/近失示范，挖掘能区分结局的假设（限制在 S* 内）
            pos, neg = contrastive_pairs(seg, demos)
            A = mine_assumptions(pos, neg, features=self.S_star,
                                 max_assumptions=self.max_A,
                                 require_causal_support=True)
            # 3) 为每个假设构造监视器与检验；不可监视/不可检验的假设直接丢弃
            Mon, Test = [], []
            for a in A:
                m = fit_monitor(a, pos, neg, calibration=seg.calib)
                tau = self._design_test(a, seg, self.cwm)
                if m is None or tau is None:
                    A.remove(a)
                    continue
                Mon.append(m)
                Test.append(tau)
            # 4) 构造后置条件、回退、支持集、来源
            post = self.cert.derive_postcondition(beta)
            fallback = self.cert.certified_fallback(seg)
            S = support_set(seg, features=self.S_star)
            kappa = Contract(beta, A, Mon, Test, post, fallback, S,
                             eps_IL=seg.imitation_error,
                             delta_IL=seg.confidence,
                             prov=self.prov.record(seg, A, Mon, Test))
            contracts.append(kappa)
        return contracts


# IP-368 ContractOptionCertifier
class ContractOptionCertifier:
    def __init__(self, v11_certifier, cwm, hdt, limits):
        self.cert = v11_certifier
        self.cwm = cwm
        self.hdt = hdt
        self.limits = limits                      # alpha_max, d_max, c_min, iota_min ...

    def certify(self, kappa):
        # C1：底层原语与 post 必须是 v11 认证的
        if not self.cert.certify_skill_macro(kappa.beta):
            return None
        if not self.cert.certify_postcondition(kappa.post):
            return None
        # C2：每个假设必须有认证监视器
        for m in kappa.Mon:
            if not self._monitor_certified(m):
                return None
        # C3：检测安全裕度——用 CWM/HDT 做失效传播/可达性检查
        for a, m in zip(kappa.A, kappa.Mon):
            if not self._detection_safety_margin(a, m, kappa):
                return None
        # C4：每个统计假设必须有安全检验
        for a, tau in zip(kappa.A, kappa.Test):
            if a.is_statistical and not self._falsifiable(a, tau):
                return None
        # C5：回退可达且 v11 认证
        if not self._fallback_reachable(kappa):
            return None
        # C6：覆盖与来源
        if kappa.coverage < self.limits.c_min or not kappa.prov.audit_ok():
            return None
        # C7：不弱化 v11 硬证书
        if not self._no_weakening(kappa):
            return None
        return ContractCert(kappa, monitor_certs=self._monitor_certs(kappa),
                            detection_margins=self._margins(kappa),
                            fallback_cert=self.cert.certify_fallback(kappa.fallback))

    def _detection_safety_margin(self, a, m, kappa):
        # 若 a 失效，系统在 d + t_fb 步内是否仍在 v11 安全集？
        for h in self.cwm.reachable_states(kappa.beta, assumption=a, violated=True):
            if self.cwm.time_to_unsafe(h) <= m.d + kappa.t_fb:
                return False
        return True

    def _falsifiable(self, a, tau):
        return (self.cert.certify_action_sequence(tau) and
                information_gain(a, tau) >= self.limits.iota_min and
                self.cwm.reversible_or_safe(tau))


# IP-369 AssumptionAwareShieldedPlanner
class AssumptionAwareShieldedPlanner:
    def __init__(self, v11_planner, certifier, vo_i_solver, reserve_budget):
        self.planner_v11 = v11_planner
        self.cert = certifier
        self.voi = vo_i_solver
        self.B_reserve = reserve_budget

    def plan(self, s, b_A, contracts, budget, deadline):
        # 盾：只保留 v11 认证且契约谓词允许的动作
        def shield(b):
            actions = []
            for k in contracts:
                if self.cert.exec_eligible(k, s, b):
                    actions.append(Exec(k))
            for k in contracts:
                for tau in k.Test:
                    if self.cert.test_admissible(k, tau, s, b):
                        actions.append(Test(k, tau))
            if budget.ask > 0:
                actions.append(Ask())
            actions.append(Fallback(self.planner_v11.certified_fallback(s)))
            return actions

        # 盾式 POMCP：动作只在 Sh(b) 内展开；b_A 由监视器/检验观测更新
        def simulate(b, depth):
            if depth == 0 or b.deadline_exceeded:
                return 0.0
            best = -inf
            for a in shield(b):
                if isinstance(a, Fallback) and budget.remaining <= self.B_reserve:
                    continue                    # 储备预算不得被规划器主动花掉
                q = self._q_value(a, b) + self._gamma * simulate(self._belief(b, a), depth - 1)
                best = max(best, q)
            return best

        return self._pomcp_root(s, b_A, shield, simulate, deadline)

    def _q_value(self, a, b):
        if isinstance(a, Exec):
            return b.expected_progress(a.k) - b.risk * self.lambda_r
        if isinstance(a, Test):
            return self.voi(a.tau, b)       # 已扣检验成本与风险
        if isinstance(a, Ask):
            return self.voi_ask(b)
        return b.fallback_value


# IP-370 ActiveContractRepair
class ActiveContractRepair:
    def __init__(self, coc, cwm, hdt, conformal_calibrator):
        self.coc = coc
        self.cwm = cwm
        self.hdt = hdt
        self.cal = conformal_calibrator
        self.repair_log = []

    def on_intervention(self, event, kappa):
        # 只更新契约元数据；不得删除 fallback / 放宽 C3 / 放宽 C1
        if event.type == "missing_assumption":
            a_new = self._infer_assumption(event)
            m_new, tau_new = self._fit_monitor_and_test(a_new, event)
            if m_new is None or tau_new is None:
                return self._mark_inadmissible(kappa)
            kappa = kappa.add_assumption(a_new, m_new, tau_new)
        elif event.type == "monitor_false_negative":
            kappa = kappa.recalibrate_monitor(event.i, self.cal, tighten=True)
        elif event.type == "monitor_false_positive":
            kappa = kappa.recalibrate_monitor(event.i, self.cal, tighten=False)
        elif event.type == "test_weak":
            kappa = kappa.replace_test(event.i, self._stronger_test(event))
        elif event.type == "support_shift":
            kappa = kappa.shrink_support(event.context)
        elif event.type == "policy_error":
            kappa = kappa.update_base_params(event.correction)
        # 修复后必须重新认证；认证失败 ⇒ 契约不可准入
        cert = self.coc.certify(kappa)
        self.repair_log.append((event, cert))
        return kappa if cert else self._mark_inadmissible(kappa)

    def augment(self, kappa, demos, n_samples):
        # 反事实样本只训练监视器/检验器；不参与证书签发
        samples = self.cwm.rollout_counterfactual(demos, kappa.A,
                                                  n=n_samples, prov="sim")
        samples += self.cwm.near_miss_negative_mining(kappa, demos)
        for s in samples:
            s.weight *= self._sim_real_weight(s)     # 仿真可信度权重
        kappa = kappa.update_monitors_from(samples, real_only=False)
        # 重新认证时只用实机标定；仿真权重不影响证书
        return self.coc.certify(kappa) and kappa or self._mark_inadmissible(kappa)
```

## 4. 推导

**引理 104（监视器风险界）** 设契约有 m 个统计假设，每个监视器 `(α_i,β_i,d_i)`-认证，契约执行时域为 T。若监视器误差在标定分布上与执行过程可交换，则一次契约执行中“出现未被检测/未回退的假设失效”的概率满足
```
P_undetected ≤ Σ_{i=1}^m ( α_i·T + P(detect_delay_i > d_i) ) + Σ_i β_i
```
若 COC 强制 `Σ_i α_i·T ≤ δ_contract` 且硬不变量假设 `α_i=0`，则 `P_undetected ≤ δ_contract + Σ_i β_i`。证明：对每个假设、每个时刻用并集界；`hold|¬a` 的漏报率 α_i 给出未检测概率上界，检测延迟尾概率单独计入；误报 β_i 只影响可用性，不影响安全性，但计入总风险预算。∎

**引理 105（检测延迟下的回退安全）** 若契约满足 C3（假设失效后 `d_i+t_fb` 步内仍在 v11 安全集）且 fallback 是 v11 认证的，则在监视器于 d_i 内检出失效的条件下，回退执行全程处于 v11 安全集，因而不会发生 v11 证书之外的事故。证明：由 C3，失效后安全窗口覆盖检测延迟与回退时间；由 C5，回退可从管内任意可达状态进入；由 v11 引理 101，v11 认证回退本身安全。合并引理 104 得总失效概率 ≤ δ_contract + δ_fb。∎

**引理 106（物理执行集不扩张）** v12 的每个物理执行动作都属于 v11 认证动作集：
```
ExecSet_phys(v12) ⊆ ExecSet_phys(v11)
```
证明：DCC 只允许 β 由 v11 HAS 原语组成（定义 571）；COC 的 C1 要求 β/post 通过 v11 四重证书（定义 573）；AASP 只在盾内选择动作，盾要求 v11 认证（定义 584）；ACRA 只改契约元数据，不改 v11 证书（定义 578）；`ask` 是无物理运动的信息动作。因此任何 v12 物理动作都可被 v11 证书验证。∎

**引理 107（储备预算下的完备性）** 设 AASP 的预算分为 `B_exec + B_reserve`，且 `B_reserve` 不小于 v11 回退/重规划的最坏成本。若 v11 在给定任务与截止期内存在完成策略，则 v12 也存在完成策略，且其契约层不会耗尽回退所需预算。证明：AASP 的约束禁止规划器主动消耗 B_reserve（定义 575/584）；当契约层失败或无可行契约时，盾中仍有 v11 fallback 动作；由归纳，v12 可退回 v11 策略完成。故完备性不低于 v11；契约层只可能因额外信息收益而改善，不会使原本可完成的 v11 任务不可完成。∎

**引理 108（检验动作安全性）** 若检验 τ 被 AASP 选择，则 τ 是 v11 认证的、状态变化可逆或可安全回退的，且其风险已计入当前风险预算；因此检验动作不会单独导致 v11 证书违规。证明：由定义 576 的可选择条件与定义 584 的盾条件，τ 必须通过 v11 证书与可逆性/回退检查；风险预算在规划时扣除；执行时仍由 50Hz v11 守卫复核。∎

**命题 1（VOI 贪心检验的近似）** 若检验的信息增益函数在假设集上自适应子模，且检验之间条件独立，则贪心选择检验达到最优期望信息增益的 `1−1/e` 近似。一般情形下 AASP 使用盾式 POMCP，具有渐近一致性但无多项式最坏保证；因此本轮只对子模情形作预注册声明，其他情形以经验 E630 评估。证明：自适应子模贪心的标准 `1−1/e` 界；POMCP 的渐近一致性来自 Robbins–Monro/UCT 的收敛条件。∎

**引理 109（契约修复的收敛与不弱化）** 设契约类可实现（存在与示范和干预一致的契约），干预从“监视器 unknown/violate 或近失”状态分布中采样，且每次修复只加强（定义 578）。则在 N 次干预后，契约的期望失效/违规率满足
```
E[violation_N] ≤ ε_approx + O( sqrt( log(1/δ) / N ) )
```
且安全集单调不增：`SafeSet_{N+1} ⊆ SafeSet_N`。证明：每次修复要么排除一个不一致假设，要么收紧一个监视器/检验；版本空间单调收缩；标准在线学习/DAgger 的 disagreement 界给出 O(√(log(1/δ)/N))；只加强保证安全集不扩张。∎

**引理 110（反事实增广不扩张证书集）** 反事实标签 `prov=sim` 只进入监视器/检验器训练与契约提议；COC 重新认证时只使用实机标定与 v11 证书；若仿真-实机校准不通过，相关权重归零。因此
```
CertifiedSet(v12 with CF) ⊆ CertifiedSet(v12 without CF) ∪ {由实机数据新认证的契约}
```
即反事实增广不能单独扩张可执行集。证明：CF 标签没有证书签发权（定义 579）；COC 的 C1–C7 不读取 `prov=sim` 作为证书证据；校准失败时权重为 0；因此新增契约仍需实机认证。∎

**引理 111（预算守恒 v12）** DCC 离线；COC 在契约准入/5Hz 摊销 ≤0.5ms；AASP 替代 v11 NCP 的 5Hz 规划槽，增量 ≤2ms；ACRA 异步摊销 ≤1ms；50Hz 守卫增量 ≤0.3ms。静态 EDF 校验 `ΣŴ_m ≤ B_dec` 后，决策侧 p99 仍 ≤22ms，50Hz 不丢拍。证明：逐项代入复杂度表；DCC/ACRA 移出在线关键路径；AASP 用 top-k 契约与缓存检验限制分支；v11 原有 2ms 余量吸收增量。∎

**引理 112（单点旁路等价 v11）** 当 `v12^⊥` 注入时，`K_IL=∅`、AASP 返回 `plan_v11`、无 test/ask、ACRA 为恒等；主闭环中所有 v12 分支均走空路径，调用序列与 v11 逐位一致。证明：定义 582 直接给出空契约集与恒等规划器；`metricvoicegauge_round_12` 在旁路自检失败时直接调用 `metricvoicegauge_round_11`；由 v11 引理 102 可继续退化到 v10/v9/v8/v7/v6。∎

**引理 113（契约组合安全）** 若 κ1、κ2 均可准入且满足定义 581 的组合条件，则 `κ1∘κ2` 可准入；组合执行中任一时刻的安全谓词由当前活跃子契约的 `SafeExec` 与 v11 证书合取保证。证明：组合的基序列是两段 v11 认证原语的拼接；交接条件保证 post1 满足 pre2；回退是活跃子契约回退；由引理 105/106 逐段应用，归纳得全程安全。∎

## 8. 已知风险与失效模式

1. **关键假设漏检（unknown unknowns）**：示范者自己也不知道的隐含条件没有被抽进 A；监视器在分布外仍报 hold，规划器选择执行。缓解：对比/近失负例挖掘、关键假设强制硬不变量、独立多模态证据、人工审计、保守支持集、把“无法解释的成功”标记为不可准入。
2. **监视器漏报与检测延迟**：统计监视器在分布外校准失效，失效在 d 步内已不可逆。缓解：C3 检测安全裕度硬约束；关键假设用硬不变量；d 与 α 计入风险预算；unknown 超时强制回退；回退速度优先于任务收益。
3. **检验的副作用与不可逆性**：检验本身改变接触/物体状态，或把系统带入不可回退区域。缓解：只允许 v11 认证、可逆或可安全回退的检验；检验风险计入预算；不可逆状态禁止检验；检验后重新走盾。
4. **契约修复过拟合/冲突**：稀疏干预、人的偏好或错误纠正导致契约过度特化；多次修复互相冲突。缓解：修复只加强、不弱化；保形校准；修复审计与回滚；把冲突干预标记为上下文分裂而非全局修改。
5. **反事实自我确认**：CWM/HDT、监视器、检验器共享同一仿真偏差，仿真负例看似覆盖了真实失效。缓解：实机校准集、独立证据通道、仿真-实机差异模型、负对照（已知不应触发的假设）、仿真权重上限。
6. **契约层过度保守导致空可行集**：C1–C7 与 v11 四重证书合取可能清空候选，AASP 只能回退，收益归零。缓解：分层契约（硬/软假设）、增量准入、HATD 重新分段、v11 回退保底、监控准入率与 K* 分布。
7. **规划器信念模型错误**：b_A 的观测模型与真实监视器误差不匹配，VOI 高估检验价值或低估风险。缓解：信念模型在线校准、保守 VOI 下界、POMCP 鲁棒化、风险预算硬约束、失败即回退。
8. **人类干预的偏差与成本**：干预稀疏、滞后、带偏好；ask 过于频繁会打扰人。缓解：VOI 阈值、批量求助、干预预算、把 ask 作为信息动作而非安全依赖、尊重拒绝/撤回。
9. **数据来源/授权/泄漏**：示范含隐私、未授权数据，或测试任务出现在示范/增广中导致虚高。缓解：prov 审计、授权与匿名化、任务/物体/场景分层拆分、预注册 held-out、数据谱系与删除机制。
10. **单点旁路的实现漂移**：旁路关闭时仍有 v12 隐式状态影响 v11 路径（缓存、预算、随机数）。缓解：旁路关闭走独立入口 `metricvoicegauge_round_11`；回归测试逐位比对；无共享可变状态；E637 门禁。

## 9. 本轮最大风险

**一句话**：契约抽取可能漏掉一个连人类示范者自己都未意识到的关键假设，监视器在分布外仍报 `hold`，规划器据此选择“执行”而不是“检验”，系统就在“有契约、有证书”的表象下执行了未被任何证书覆盖的行为——**自信地持有一份漏掉关键假设的契约**。
