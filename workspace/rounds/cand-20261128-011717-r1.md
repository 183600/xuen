### 第 1 轮灵感驱动研究记录（新循环第 1 轮，继承上一循环 CADVS-v4）

**灵感词**：通用机器人平台、运动控制

**继承关系**：上一循环第 4 轮 CADVS-v4（IP-489~492）在 v3 五锚点（3DCF/MSRG/HICK/EEK/LTEM）上加入价值锚 VACK 与平衡锚 BCK，形成七硬门 kc_evidence_forged_v4 = kc_coverage ∧ kc_physics ∧ kc_human ∧ kc_ee ∧ kc_mem ∧ kc_val ∧ kc_bal，fail-closed；执行集 Exec_CADVS-v4 ⊆ Exec_CADVS-v3 ⊆ Exec_CADVS-v2 ⊆ Exec_CADVS-v1 ⊆ Exec_v29。但 v4 仍隐含两个「单机、理想执行」假设：(H1) 证书只在同一具身上铸造与消费；(H2) 任务级证书的「可执行性」由底层运动控制器默认保证。通用机器人平台打破 H1：同一技能要在异构具身（不同自由度、连杆、执行器、传感器、接触模型）间复用；运动控制打破 H2：一条被证书判定「安全」的轨迹，未必能被具体平台在力矩/速度/跟踪误差约束内真正执行。本轮提出 CADVS-v5（IP-493~496），把「证据可信」升级为「部署可信」，执行集升级为 Exec_CADVS-v5 ⊆ Exec_CADVS-v4 ⊆ … ⊆ Exec_v29。

**直觉与动机**：

1. **通用平台 = 证书可迁移**。直觉：一个抓取技能在 Panda 上被七硬门铸造，搬到 UR5e、四足、人形上时，如果每次从零重铸，所谓「通用平台」就退化成「N 个专用平台」。真正可复用的是「证据」而不是「参数」。做法：把具身差异压缩成一个可度量距离 d_E(E_A,E_B)——运动学树编辑距离、参考构型上的雅可比差异、惯性参数 Wasserstein 距离、执行器包络散度、传感器组散度——再让证书通过迁移函子 F_{A→B} 搬到目标具身。搬运会损失边际，损失量由各锚边际关于 d_E 的 Lipschitz 常数控制。硬门 kc_xfer 检查「源边际 − L·d_E − 函子缺陷 ≥ τ_xfer」。这样迁移不是拍脑袋，而是带显式误差预算的保守保证。

2. **运动控制 = 证书可执行**。直觉：证书只保证「任务级规则在覆盖/物理/人因/末点/记忆/价值/平衡上合法」，但没保证「底层控制器跟得上」。在异构平台上，同一条参考轨迹可能因执行器饱和、带宽不足、背隙/摩擦导致跟踪误差超出任务容差，或速度/力矩超限。做法：用控制收缩度量（CCM）刻画闭环微分动力学，得到有限时域跟踪误差管 r_T = r_0 + d_max/λ；再对输入/速度做约束收紧，并沿误差管取接触锥最坏情况。硬门 kc_motion 检查 r_T ≤ ε_task、输入与速度在收紧包络内、λ ≥ λ_min、且接触边际沿管为正。

3. **统一：可部署 = 可迁移 ∧ 可执行**。把 ETK/MEK 实现为证书演算上的两个函子（transport functor 与 realization functor），而不是两个孤立硬门：它们作用在既有七锚证书上，并保持格结构（meet 同态），因此新增的是「算子」而非「证据源」。这直接缓解 v4 风险表 R52 的「锚点维护负债」——九硬门不是九个互不相干的模块，而是「七锚证书 + 两个结构变换」。

4. **三难权衡**。直觉：通用性（能接受的具身距离 g = d_E 越大）、敏捷性（收缩率 a = λ 越大、动作越快）、安全性（剩余边际 s 越厚）三者共享同一安全预算。给出部署可行域前沿 L·g + c·a ≤ s_0，明确「通用平台不可能同时做到又通用、又快、又安全」。这不是工程抱怨，而是一条可写进论文的 no-free-lunch 式约束。

**关键洞见**：v4 回答「在这台机器人上，这条规则是否可信」；v5 回答「换一台机器人、并且要真的动起来，这份可信是否还能兑现」。证书从「静态证据」变成「可迁移、可执行的可部署凭证」。这把前四轮的单机证据链，升级为跨具身的部署证据链。

**形式化目标（增量）**：

1. 定义具身描述子 E = (G, ℓ, μ, A, S, C) 与具身距离 d_E(E_A,E_B)。
2. 定义部分具身态射 φ_{A→B}: E_A ⇀ E_B（允许未匹配结构）与证书迁移函子 F_{A→B}: Cert_A → Cert_B，及其函子缺陷 ρ_i。
3. 定义迁移下界边际 m_i^↓ = m_i − L_i·d_E − ρ_i，硬门 kc_xfer = (∀i m_i^↓ ≥ τ_xfer) ∧ (d_E ≤ d_E^max)，软因子 η_xfer。
4. 定义控制收缩度量 M(x) ≻ 0、收缩率 λ、误差管 r_T、约束收紧系数 σ，硬门 kc_motion，软因子 η_motion。
5. 证明迁移 Lipschitz 引理、误差管引理、迁移函子保持 fail-closed 定理、部署三难前沿定理、执行集严格收缩定理。
6. 定义 EFA-v5 九硬门与 ECS_v5 = ECS_v4 · η_xfer · η_motion。
7. 定义 Exec_CADVS-v5 = Exec_CADVS-v4 ∩ {x : kc_xfer(x)} ∩ {x : kc_motion(x)}，并证明严格嵌套。

**本轮最大风险**：迁移 Lipschitz 界在接触/摩擦等非光滑动力学处不可靠，kc_xfer 可能同时过度保守（通用平台名存实亡）与虚假放行（异构具身上未验证规则被迁移），这是本轮方案的阿喀琉斯之踵。

## 2. 关键算法骨架

### IP-493 ETK：具身迁移核（部署时，异步 ~10–80 ms/规则）

```python
@dataclass
class EmbodimentDescriptor:
    G: Any            # 运动学树：节点=连杆，边=关节（轴/限位/传动比）
    ell: np.ndarray   # 连杆几何参数（长度、质心偏移、关节轴）
    mu: np.ndarray    # 惯性参数展平 (m, com, I)
    A: Any            # 执行器包络 {tau_max, dtau_max, qd_max, bw, backlash, derating}
    S: Any            # 传感器组（编码器/F-T/触觉/IMU/视觉）
    C: Any            # 接触模型（足/手接触几何、摩擦系数、柔顺）

@dataclass
class EmbodimentTransferKernel:
    """ETK：具身距离 + 证书函子 + 迁移硬门 kc_xfer"""
    tau_xfer: float = 0.15
    dE_max: float = 0.35
    L: dict = field(default_factory=dict)   # 各锚 Lipschitz 常数（离线标定上界）
    L_default: float = 2.0

    def build(self, robot) -> EmbodimentDescriptor:
        return EmbodimentDescriptor(G=self._tree(robot), ell=self._geometry(robot),
                                    mu=self._inertial(robot), A=self._actuators(robot),
                                    S=self._sensors(robot), C=self._contact(robot))

    def distance(self, EA: EmbodimentDescriptor, EB: EmbodimentDescriptor) -> float:
        dG  = self._tree_edit(EA.G, EB.G)          # 归一化 Zhang-Shasha 树编辑距离
        dJ  = self._jacobian_gap(EA, EB)           # 参考构型集上 sup 归一化 Frobenius 差
        dMu = self._w2(EA.mu, EB.mu)               # 惯性参数点云 Wasserstein-2
        dA  = self._actuator_gap(EA.A, EB.A)       # 包络对数比 + 带宽/背隙/降额
        dS  = self._sensor_gap(EA.S, EB.S)         # Jaccard + 噪声模型散度
        return 0.25*dG + 0.30*dJ + 0.20*dMu + 0.15*dA + 0.10*dS

    def morphism(self, EA, EB) -> Morphism:
        # 图匹配（子树同构 + 语义标签）+ 关节对应；未匹配节点标 UNMATCHED
        return self._graph_match(EA.G, EB.G)

    def transport(self, cert, EA, EB, phi) -> Cert:
        # 逐锚把几何/动力学量经 phi 搬运；未匹配锚取保守默认并计入 ρ_i
        transported = {}
        rho = {}
        for i, anchor in enumerate(cert.anchors):
            if phi.matches(i):
                transported[i], rho[i] = self._push(anchor, phi, EA, EB), 0.0
            else:
                transported[i], rho[i] = self._conservative_default(anchor), self._rho_default(i)
        return Cert(rule=cert.rule, anchors=transported, rho=rho, margins=cert.margins)

    def kc_xfer(self, cert, EA, EB) -> tuple[bool, float]:
        dE = self.distance(EA, EB)
        if dE > self.dE_max:
            return False, 0.0
        cert_B = self.transport(cert, EA, EB, self.morphism(EA, EB))
        m_down = [mA - self.L.get(i, self.L_default)*dE - cert_B.rho[i]
                  for i, mA in enumerate(cert.margins)]
        m_min_down = min(m_down)
        return (m_min_down >= self.tau_xfer,
                float(np.clip(m_min_down / (cert.m_min + 1e-9), 0.0, 1.0)))
```

### IP-494 MEK：运动执行核（轨迹提交时 + 控制环轻量校验，目标增量 < 0.5 ms）

```python
@dataclass
class MotionExecutionKernel:
    """MEK：CCM 误差管 + 约束收紧 + 接触锥沿管最坏情况；kc_motion"""
    lambda_min: float = 2.0
    sigma: float = 0.10
    eps_task: float = 0.01
    d_max: float = 0.02
    metric: Any = None            # 离线解出的 CCM M(x)（SDP / Neural CCM），在线仅评估

    def certify(self, traj, controller, E, bck, t_now) -> MFC:
        # 1) 沿参考轨迹采样，评估 M(x) 与闭环收缩率 λ（离线已保证 CCM 条件）
        lam = self._contraction_rate(traj, controller, self.metric)
        # 2) 误差管（引理 44）：r_T = r_0 + d_max/λ
        r_T = traj.r0 + self.d_max / max(lam, 1e-6)
        # 3) 名义输入 + 反馈修正上界，做约束收紧
        u_peak = self._input_peak(traj, controller, r_T)
        qd_peak = self._velocity_peak(traj, r_T)
        # 4) 沿管最坏接触锥边际（复用 BCK，放大鲁棒边际）
        xi_contact = self._worst_contact_margin(traj, bck, r_T)
        # 5) 归一化边际取最紧约束
        xi = min((self.eps_task - r_T) / self.eps_task,
                 min_i((1-self.sigma)*E.A.tau_max[i] - u_peak[i]) /
                       ((1-self.sigma)*E.A.tau_max[i]),
                 min_i((1-self.sigma)*E.A.qd_max[i] - qd_peak[i]) /
                       ((1-self.sigma)*E.A.qd_max[i]),
                 (lam - self.lambda_min) / self.lambda_min,
                 xi_contact)
        return MFC(r_T=r_T, lambda_=lam, xi=xi, t=t_now)

    def kc_motion(self, mfc: MFC) -> bool:
        """引理 44：通过 ⟹ 跟踪误差在管 r_T 内、输入/速度在收紧包络内、接触稳定"""
        return mfc.xi >= 0.0

    def _contraction_rate(self, traj, controller, M) -> float: ...
    def _input_peak(self, traj, controller, r_T) -> np.ndarray: ...
    def _velocity_peak(self, traj, r_T) -> np.ndarray: ...
    def _worst_contact_margin(self, traj, bck, r_T) -> float: ...
```

### IP-495 DEPCALC：部署演算与核心定理（离线理论，不在控制环）

```python
class DeploymentCalculus:
    """部署演算：在 CERTCALC 的证书格上加入 transport / realization 两个函子"""

    @staticmethod
    def transport(c, EA, EB, etk):            # F_{A→B}
        return etk.transport(c, EA, EB, etk.morphism(EA, EB))

    @staticmethod
    def realize(c, E, mfc):                   # R_E：附加运动可执行约束
        return CertCalc.meet(c, Cert.from_motion(mfc, E))

    @staticmethod
    def deploy(c, EA, EB, E_target, mfc, etk, mek):  # 可部署 = 可迁移 ∧ 可执行
        c_B = DeploymentCalculus.transport(c, EA, EB, etk)
        c_R = DeploymentCalculus.realize(c_B, E_target, mfc)
        return CertCalc.meet(c_R, Cert.from_transfer(etk.kc_xfer(c, EA, EB)))

# 定理 5（函子保持 fail-closed）：F(⊤)=⊤, F(⊥)=⊥, F(c1∧c2)=F(c1)∧F(c2)，
#   故 F 为证书格的 meet 同态；源证书含 ⊥ 时目标证书必含 ⊥，不会静默放行。
# 定理 6（部署三难前沿）：在边际预算 m_min = L·g + c·a + s 下，
#   可行域为 L·g + c·a ≤ m_min − τ，前沿 g_max(a) = (m_min − τ − c·a)/L 单调递减。
```

### IP-496 EFA-v5：九硬门 + 软评分 + 证据铸造流水线 v5

```python
@dataclass
class EvidenceForgingAssemblerV5:
    """EFA-v5：九硬门 fail-closed；ECS_v5 = ECS_v4 · η_xfer · η_motion"""
    efa4: EvidenceForgingAssemblerV4
    etk: EmbodimentTransferKernel
    mek: MotionExecutionKernel

    def hard_gate(self, x, t_now, rule_id, hic, eec: EEC, bcc: BCC, mfc: MFC,
                  traj, context, EA, EB) -> tuple[bool, str]:
        # 优先级：HIC veto 仍最高；v4 七门全部通过后才检查 v5 两门
        ok4, reason = self.efa4.hard_gate(x, t_now, rule_id, hic, eec, bcc,
                                          traj=traj, context=context)
        if not ok4:
            return False, reason
        ok_x, eta_x = self.etk.kc_xfer(self.efa4.cert_of(rule_id), EA, EB)
        if not ok_x:
            return False, 'EMBODIMENT_UNTRANSFERABLE'
        if not self.mek.kc_motion(mfc):
            return False, 'MOTION_INFEASIBLE'
        return True, 'DEPLOYABLE'

    def ecs_v5(self, x, t_now, rule_id, A_att=0.0, eta_mem=0.5,
               eta_val=0.5, eta_bal=0.5, eta_xfer=0.5, eta_motion=0.5) -> float:
        base = self.efa4.ecs_v4(x, t_now, rule_id, A_att, eta_mem, eta_val, eta_bal)
        return base * eta_xfer * eta_motion
```

### 集成流水线（v4 → v5）

```
离线/慢时域（具身描述子 + CCM + 联邦先验，不在控制环）：
  各站 i：E_i = build(robot_i)；离线解 CCM M_i(x)；本地 Δ_i（含 E_i/迁移缺陷统计）
       ──▶ DP 扰动 ──▶ 安全聚合 ──▶ FedAvg ──▶ Φ_global（含 portability map）
       ──▶ 下发：Γ_3D 先验、Θ_domain、λ_vec^0、W^0/ZMP^0、E_class 边际先验

部署时（异步，~10–80 ms/规则）：
  源证书 c_A ──▶ ETK.distance(E_A,E_B) ──▶ F_{A→B}(c_A) ──▶ m_i^↓
       ──▶ kc_xfer（含 d_E 上限）──▶ 通过则写入目标具身 KC 库；否则触发 few-shot 修复/重铸

轨迹提交时（每段轨迹一次，~0.1–0.4 ms）：
  参考轨迹 + 控制器 ──▶ MEK.certify ──▶ MFC（r_T, λ, ξ_motion）──▶ kc_motion

在线控制环（每周期，增量 < 0.5 ms）：
  EEK 读力/力矩/触觉 → EEC → kc_ee
  BCK 读全身状态/接触 → BCC → kc_bal
  读缓存 MFC（轨迹提交时已算），仅做 O(1) 的 kc_motion 复核
  证书消费前：EFA-v5.hard_gate(...)
      ├─ v4 七门失败          → 按 v4 既有策略处理
      ├─ EMBODIMENT_UNTRANSFERABLE → 拒绝部署 / 触发 few-shot 修复 / 回退源具身
      └─ MOTION_INFEASIBLE    → 降速/软化阻抗/重规划轨迹 + 教师介入
```

## 4. 正确性论证（增量更新）

### 引理 43（迁移 Lipschitz 界）

**陈述**：设证书各锚边际 m_i(E,c) 在 E 的邻域内关于具身距离 d_E 满足 L_i-Lipschitz，且迁移函子 F 在匹配结构上精确、未匹配结构的近似缺陷为 ρ_i。则对目标具身 E_B：

m_i(E_B, F(c)) ≥ m_i(E_A, c) − L_i·d_E(E_A,E_B) − ρ_i = m_i^↓。

**证明**：由三角不等式，|m_i(E_B,F(c)) − m_i(E_A,c)| ≤ |m_i(E_B,F(c)) − m_i(E_B,c)| + |m_i(E_B,c) − m_i(E_A,c)| ≤ ρ_i + L_i·d_E；取单侧下界即得。∎

**工程含义**：kc_xfer 用的是保守下界，通过即意味着目标具身上的真实边际不低于 τ_xfer。**诚实边界**：L_i 是局部、数据相关的常数；接触/摩擦切换使 m_i 非光滑，Lipschitz 假设在最关键处最可能失效。

### 引理 44（跟踪误差管与执行可行性）

**陈述**：对控制仿射系统 ẋ = f(x) + B(x)u，若存在 CCM M(x) ≻ 0 与微分反馈使闭环满足 d/dt(δxᵀMδx) ≤ −2λ·δxᵀMδx + γ‖δd‖²，且初始误差 ‖e(0)‖_M ≤ r_0、扰动 ‖d‖ ≤ d_max，则

‖e(t)‖_M ≤ r_0·e^{−λt} + (d_max/λ)(1−e^{−λt}) ≤ r_0 + d_max/λ = r_T。

**证明**：对 V = eᵀMe 应用比较引理，解一阶微分不等式，取 t→∞ 得上界。∎

**工程含义**：r_T 给出可证跟踪误差管；对输入/速度做收紧 (1−σ)u_max 后，若名义输入峰值加反馈修正仍在包络内，则执行器不饱和；沿管取 BCK 接触锥最坏情况保证接触稳定。**诚实边界**：CCM 条件在接触模式切换（足着地/离地、抓取建立/断开）时需分段/混合 CCM，单一 M(x) 可能不可行或过度保守。

### 定理 5（迁移函子保持 fail-closed）

**陈述**：迁移函子 F: Cert_A → Cert_B 满足 F(⊤)=⊤、F(⊥)=⊥、F(c₁∧c₂)=F(c₁)∧F(c₂)，即为证书格的 meet 同态。因此源证书因任一硬门失败而含 ⊥ 时，目标证书必含 ⊥，迁移不会把失败静默变成通过。

**证明**：transport 对锚逐分量作用且保守默认映射到 ⊥；meet 在分量上逐点取小，故与 transport 交换；⊤/⊥ 为固定点。∎

### 定理 6（部署三难前沿）

**陈述**：设部署安全预算为 m_min，通用性 g = d_E，敏捷性 a = λ，迁移消耗 L·g，运动消耗 c·a（c 为运动激进度系数），剩余安全边际 s = m_min − L·g − c·a。则可行部署域为

L·g + c·a ≤ m_min − τ，

其 Pareto 前沿 g_max(a) = (m_min − τ − c·a)/L 关于 a 单调递减。即通用性与敏捷性不可同时无界提升，二者都以安全性为共同预算。

**证明**：由引理 43（迁移下界随 d_E 线性下降）与引理 44（误差管随 λ 下降、但输入峰值随 λ 上升，约束收紧后运动边际随 λ 线性下降）直接相加得预算不等式；对 a 求导得单调性。∎

**工程含义**：给定平台与任务，操作点 (g, a) 应落在前沿内侧并保留 s 余量；跨具身距离越大，就必须牺牲动作速度/收缩率，反之亦然。

### 定理 v5（执行集严格收缩与九锚点完备）

**陈述**：在 (B1)~(B6) 继承 v4 假设，并新增 (B7) 各锚边际关于 d_E 局部 Lipschitz 且 L_i 上界有效；(B8) 目标轨迹存在可行 CCM 且扰动有界 下：

(i) Exec_CADVS-v5 ⊆ Exec_CADVS-v4 ⊆ … ⊆ Exec_v29，且当 kc_xfer、kc_motion 非恒真时严格收缩；
(ii) kc_xfer 通过 ⟹ 目标具身真实边际 ≥ τ_xfer（引理 43）；
(iii) kc_motion 通过 ⟹ 跟踪误差在 r_T 内、输入/速度在收紧包络内、接触稳定（引理 44）；
(iv) 迁移函子保持 fail-closed（定理 5）；
(v) 部署三难前沿成立（定理 6）；
(vi) 九锚点 {3DCF, MSRG, HICK, EEK, LTEM, VACK, BCK, ETK, MEK} 覆盖「感知→仿真→人因→实机接触→跨时经验→价值→平衡→跨具身→可执行」完整部署证据链，缺一不可。

**证明**：(i) v5 在 v4 每条执行路径上追加 kc_xfer（部署时）与 kc_motion（轨迹提交/周期）合取项，只缩不涨；非恒真性由存在具身对 (E_A,E_B) 使 d_E > d_E^max、以及存在轨迹使 r_T > ε_task 保证。(ii)(iii) 分由引理 43、44。(iv) 定理 5。(v) 定理 6。(vi) 逐锚构造反例（见风险表 R53~R59）。∎

**诚实声明**：(B7) 是最脆弱假设——接触/摩擦/背隙使动力学非光滑，全局 Lipschitz 常数可能不存在，局部常数又可能在切换点跳变；(B8) 的 CCM 在混合接触下未必可行。缓解：按接触模式分段标定 L_i 并加 guard band；混合/切换 CCM；CCM 不可行时回退到 tube-MPC 或直接重铸。

## 5. 实验设计与初步结果（计划中，第 2~3 轮实机）

### 5.1 实验设计

- **平台**：MuJoCo 3.x + MJX（仿真）+ 异构实机队（Panda 7-DOF、UR5e 6-DOF、四足 12-DOF、人形 19-DOF、移动机械臂 9-DOF），覆盖不同执行器（谐波/SEA/准直驱）、传感器与接触模型。
- **技能集**：抓取放置、开门、推、插孔、上下台阶；每技能先在源具身（Panda）铸造 v4 证书，再迁移到其余具身。
- **对照**：v4（逐具身重铸）、v5-full（迁移 + 执行）、A1（去 ETK，强制重铸）、A2（去 MEK，运动不感知）、A3（去 ETK+MEK，纯 v4）、A4（ETK 用固定距离阈值替代 Lipschitz 界）、A5（MEK 用静态跟踪阈值替代 CCM 管）。
- **协议**：
  (a) 跨具身迁移：按 d_E 分层（近/中/远）测迁移接受率与违例率；
  (b) 运动执行：轨迹速度/加速度扫描，测执行器饱和、超速、跟踪误差管覆盖率；
  (c) 接触模式切换：足着地/离地、抓取建立/断开，测 CCM 可行率与 kc_motion 误拒率；
  (d) 三难前沿验证：固定安全阈值，扫描 (g,a) 操作点，测可行域边界是否匹配 L·g+c·a ≤ s_0；
  (e) 联邦异构：不同具身类别的 Δ_i 聚合，测 portability map 收敛与负迁移。
- **指标**：迁移接受率、迁移证书违例率、重铸成本（规则·人时）、执行器饱和率、超速率、跟踪误差管经验覆盖率、kc_motion 误拒/误放率、部署成功率、三难前沿拟合误差、控制环延迟 P99、丢帧率。

## 7. 本轮最大风险（最终确认）

**一句话**：**迁移 Lipschitz 界在接触/摩擦等非光滑动力学处不可靠，kc_xfer 可能同时过度保守（通用平台名存实亡）与虚假放行（异构具身上未验证规则被迁移），这是本轮方案的阿喀琉斯之踵。**
