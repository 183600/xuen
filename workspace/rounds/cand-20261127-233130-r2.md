## 1. 直觉与动机（先直觉，再严谨定义）

### 1.1 直觉：记忆检索与动作分块其实是同一件事

人做陌生装配时不会每 50ms 重新思考一次关节角，而是**想起一段动作**：看到锁扣，脑中调出一段「对准—下压—旋转」的程序，执行完再根据结果换下一段。这里有两件事同时发生：(a) 检索的单位是**一段动作**，不是单个动作；(b) 执行的单位也是这一段。**记忆的原子和执行器的原子是同一个东西。**

第 2 轮的 I9 把检索放在 reset，只取了「物体→抓取参数」的语义先验；I4 把分块当成长度旋钮。两个灵感一撞，真正的机会是：**把示教库切成 chunk，建成可检索的程序记忆；推理时检索的是一段相位对齐、边界连续的轨迹，而不是一个动作。** 这样检索天然回答了「检索到状态之后该干什么」，分块天然回答了「检索太频繁、延迟太高」——一次检索服务 T_a 步，延迟被摊销。

### 1.2 严谨定义

**定义 1（chunk 策略与接口契约）**：设观测空间 O、动作空间 A、基础执行频率 f。策略在查询时刻 t 返回 \(A_t=(a_{t,0},\dots,a_{t,T_a-1})\in A^{T_a}\)，执行器顺序执行全部 \(T_a\) 步后才查询下一次。查询间隔 \(\Delta=T_a/f\)，反应性 \(R=1/\Delta=f/T_a\)。要无停顿，需 \(p99(\text{推理}+\text{检索})<\Delta\)。于是 T_a 的选择是一个显式权衡：
\[
T_a^{*}=\arg\max_{T_a\in\{1,2,4,8,16\}}\ \mathbb E[\text{score}\mid T_a]\quad \text{s.t.}\ p99(\text{infer}+\text{retrieve})<T_a/f .
\]
**T_a 是全局的**（F20），不能按任务改；这使「自适应 chunk 长度」在本题中退化为「全局 T_a + 块内调度」。

**定义 2（分块记忆库）**：\(\mathcal M=\{(k_i,c_i,\phi_i,y_i,q_i)\}\)，其中 \(k_i\) 是观测键嵌入，\(c_i\in A^{H_i}\) 是示教轨迹切出的一段动作，\(\phi_i\in[0,1]\) 是该段在技能内的归一化相位，\(y_i\) 是技能/任务标签，\(q_i\) 是质量分。存储粒度 = 执行粒度。

**定义 3（相位条件检索）**：给定当前键 \(k_t\) 与相位估计 \(\hat\phi_t\)，
\[
R(k_t,\hat\phi_t)=\sum_{i\in\mathcal N_k}\frac{w_i}{\sum w_i}\,\mathrm{Warp}(c_i;\phi_i\to\hat\phi_t),\quad
w_i=\exp(-d(k_t,k_i)/\tau)\,\mathbb 1[|\phi_i-\hat\phi_t|<\delta]\,q_i,
\]
\(\mathrm{Warp}\) 是按相位把示教 chunk 时间重采样到当前相位起点。检索输出是一段**轨迹**，不是单点动作。

**定义 4（边界感知选择）**：记已执行前缀末动作 \(a^-\)、候选 chunk 首动作 \(a^+\)，拼接代价
\[
J=\|a^+-a^-\|_\Sigma+\lambda\|\Delta a^+-\Delta a^-\|_\Sigma+\mu\,\mathrm{DTW}(c_i,\text{recent executed}).
\]
检索不只按视觉相似度选，还在 top-k 中按 J 最小选——**这是相对普通行为检索的新意：检索目标含动力学连续性。**

**定义 5（键的不变性要求）**：令 \(\mathcal G\) 为背景/光照/干扰物/物体外观等泛化轴上的 nuisance 变换，\(\mathcal T\) 为技能/相位变换。检索键应满足
\[
d(k(o),k(g\cdot o))\ll d(k(o),k(o')),\quad g\in\mathcal G,\ o'=\mathcal T(o).
\]
用对比学习实现：正样本 = nuisance 增广（含 F22 的 JPEG/resize），负样本 = 不同相位/技能。

**定义 6（检索伤害率）**：\(\mathrm{Harm}=\mathbb E_{o\sim\text{标称}}[\mathbb 1(\text{检索开启}\land \text{score}(o)<\text{score}_{\text{无检索}}(o))]\)。PR6 要求 Harm 先于 Gain 被验证：**一个检索器在标称集上不能先证明自己不伤害，就不配上计分通道。**

### 1.3 一个把两个灵感焊死的推导

设每步状态偏差按一阶模型 \(D_k\le L D_{k-1}+\delta\) 演化（\(L\) 为闭环对动作偏差的放大率，\(\delta\) 为检索 chunk 与 VLA chunk 的首步差）。则一个 chunk 内累积偏差
\[
D_{T_a}\le \delta\,\frac{L^{T_a}-1}{L-1}.
\]
当 \(L>1\) 时，**固定 chunk 越长，记忆检索的一次错误被放大得越厉害**；而 F20 又不允许中途撤销。因此检索误差容限必须随 T_a 收紧：
\[
\delta\lesssim \varepsilon\,\frac{L-1}{L^{T_a}-1}.
\]
这条式子直接给出三个设计约束：(a) T_a 越大，检索门控越保守；(b) 必须做边界感知选择以压低首步差 \(\delta\)；(c) 块尾应主动收敛到安全姿态（tail-hold），使误差不在下一步继续滚雪球。**这是本轮把「记忆检索」与「动作分块」统一起来的核心论证：chunk 既是摊销检索延迟的福利，也是放大检索错误的杠杆。**

## 2. 对上一轮痛点的增量修订

- **P4（无触觉）**：分块程序记忆提供「接触段整段轨迹」先验，比单帧检索更能编码接触时序——I3 的第二条缓解路径升级。
- **P5（时间压力）**：固定 T_a（F20）让推理预算变成「每 Δ 一次」，检索延迟被 T_a 摊销；T_a 越大越省延迟但反应越慢、检索伤害越大。
- **P8（示教质量）**：质量分 \(q_i\) 进入检索权重；低质示教不再均匀污染。
- **P9（新）检索污染**：错误检索会被整段执行且不可中途撤销（F20），其伤害比单步错误更重。
- **P10（新）全局契约约束**：T_a、control_space 全局固定；一切「按任务自适应」的设计都要先问是否违反握手契约。

## 3. 研究问题（本轮 Q9–Q11，Q1–Q8 保留）

- **Q9（固定块契约下的最优 T_a）**：在 32 任务混合、p99 延迟约束、接触/搬运两类反应性需求下，全局 T_a 的最优值是多少？块内如何安排「前段保守、后段收敛」以模拟变长 chunk？检索开启后最优 T_a 是否变小（因为 \(L^{T_a}\) 放大）？
- **Q10（chunk 记忆键）**：什么键表示能在 5 条泛化轴上不变、又对技能/相位敏感？如何用 JPEG/resize/背景/外观增广做对比学习，使检索翻车率可测、可控？
- **Q11（相位对齐与边界连续）**：跨示教、跨相位的 chunk 如何对齐与拼接，才能让拼接代价 J 有界且不产生不可行动作？边界感知检索相对纯视觉检索的增益有多大？

## 4. 设计原则（新增 PR6/PR7）

- **PR6 检索保守律**：检索默认关闭；只有「距离过阈 + 与 VLA 提案一致 + 边界代价低」三者同时满足才启用。先证 Harm≈0，再谈 Gain。
- **PR7 块为原子律**：记忆存储、检索、执行、质量标注都以 chunk 为原子；逐帧记忆检索只在 chunk 内部做平滑，不作为独立决策层。
- PR1–PR5 保留。

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2）

> 检索日期：2026-11-26（第 1 轮）、2026-11-27（第 2/3 轮）；来源见 §5。承接 v1.1：I4/I9 因接口事实修正，I10 新增，I2/I5/I8 深化。清单只增改不重置。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I10 分块程序记忆检索 CMR（新） ★★★★★
- **动机**：示教库是全成功轨迹，I9 只在 reset 取一次语义先验，浪费了「状态→未来一段动作」的全部程序性知识；而 F20 的固定 chunk 契约恰好让「一段动作」成为可存储、可检索、可执行的天然单位。
- **与现有方案差异**：普通行为检索（behavior retrieval）按单帧/单步检索，检索频率高且不知未来；纯 VLA 只靠参数化泛化。CMR 按 **chunk 检索**，一次检索服务 T_a 步，检索目标同时含视觉相似度、相位一致性与边界连续性。**核心差异：检索的是「轨迹片段」，不是「动作点」。**
- **技术可行性**：中-高。chunk 库从 32 任务 + 110 语料离线切分；键用 DINOv2 patch 池化 + 指令嵌入 + 本体相位；FAISS IVF-PQ 检索 <5ms；对比学习只需单卡 LoRA/投影头。全部推理期计算，零权重更新。
- **所需资源**：chunk 切分与入库 1 GPU 日；索引内存约 2–4GB；工程 2 人周；无额外真机预算（L0 先行）。
- **落地步骤**：①定义切分边界（夹爪开合、速度极小值、得分点达成帧）；②建 chunk 库并打相位/质量标签；③训练/微调键编码器（nuisance 正样本、相位/技能负样本）；④实现相位条件 top-k + 边界代价重排；⑤三层门控（距离阈值、与 VLA 一致性、边界 J）；⑥L0 验 Harm，再上 3 任务 L2。
- **风险**：检索键被外观主导 → 在未见物品轴拉回旧示教；固定 T_a 放大错误。缓解：不变性键 + 门控 + tail-hold + 先证 Harm≈0；最大风险见 §6。

### I4 v2 固定块契约下的调度 ★★★★
- **动机**：第 2 轮「干预态短 chunk / 稳定态长 chunk」被 F20 判为不可实现——`action_chunk_size` 握手固定、执行器一次执行完整块。
- **本轮修正**：把「长度自适应」改为三个合法旋钮：
  1. **全局 T_a 选择**：在 {1,2,4,8,16} 上按 \(p99 < T_a/f\) 与 32 任务混合代理分扫描；一份提交只能选一个值。
  2. **块内保守调度**：一个 chunk 内前 ρ 比例用于对准/确认，后段才收敛到目标；接触任务 ρ 大、搬运任务 ρ 小。
  3. **tail-hold**：块尾 k 步主动收敛到稳定姿态/保持位，使下一次推理迟到时不继续漂移。代价是循环时间变长。
- **与现有方案差异**：别人把 T_a 当常数；本点把 T_a 当全局决策变量，并显式优化块内相位与块尾安全。
- **技术可行性**：高（纯推理与离线扫描）。
- **所需资源**：L0 离线扫描 + 少量真机确认；无新增训练。
- **落地步骤**：①L0 测各 T_a 的平滑度/拼接代价；②真机测 p99；③接触/搬运各 2 任务验证 ρ 与 tail-hold；④定全局 T_a。
- **风险**：tail-hold 浪费循环时间，可能损失步骤分；缓解：只在接触/高不确定段启用，搬运段关闭。

### I9 v2 语义记忆检索 ★★★★（修正）
- **动机**：未见物品轴（同类不同外观）在 32 任务 × 2/10 次中全面出现；纯参数化泛化对新外观方差大。
- **本轮修正**：F21 证明 `reset()` 拿不到首帧，因此检索改为**首个 get_action 惰性初始化**；I9 只保留语义层（物体→技能/抓取参数），程序层交给 I10，避免一个点承担两件事。
- **与现有方案差异**：纯通才策略靠训练分布平均化；本点在首帧把目标物体映射到 110 语料 + 32 任务的「物体-技能库」，得到抓取开度、接近高度/朝向、技能模式等软先验。
- **技术可行性**：中-高。开放词汇检测 + DINOv2 嵌入 + FAISS；首帧检索 <1s，结果缓存到 episode 状态，块内零额外开销。
- **所需资源**：嵌入 1 GPU 日；1 人周工程。
- **落地步骤**：①首帧物体检测与裁剪；②嵌入 + 索引；③先验参数化；④软注入；⑤L0 验证不伤标称 + 未见轴增益。
- **风险**：检测/嵌入在 JPEG（F22）下不稳；误检索注入错误先验。缓解：多帧投票、距离阈值、超阈退回无先验。

### I5 v3 分块合成恢复 ★★★★
- **动机**：数据集全成功、无失败示教；步骤分是官方得分点制（F17）；恢复能力只能靠合成「偏离→修正」示教获得。
- **本轮深化**：不再自由生成恢复动作，而是从 I10 的 chunk 库**检索 + 相位对齐 + 拼接**出恢复段：对成功 eps 在相位 φ 注入受控扰动，取扰动后状态检索 top-k chunk，按边界代价选一条续接，形成「偏离→修正」样本；只有达成下一官方得分点的合成段才保留（自动质量门禁）。
- **与现有方案差异**：v2 的扰动重放/跨段缝合仍可能产生分布外动作；v3 的恢复动作来自真实示教 chunk，分布内且动力学连续。
- **技术可行性**：中-高（数据工程 + 检索，无需世界模型）。
- **所需资源**：1×24GB GPU；2 人周；检测器训练 1 GPU 日/任务族。
- **落地步骤**：①得分点逆向；②3 个弱任务试点（PlugCharger/ZipUp/PourOutMedicine）；③检索式恢复合成；④LoRA 增量训练；⑤单任务通道 A/B。
- **风险**：合成偏离分布与真实失配；缓解：扰动幅度从 I1 考纲卡采样，合成段过得分点门禁。

### I2 v3 数据引擎 2.0：孪生迁移 + 记忆库双用 ★★★★★
- **动机**：单模型平均分被最弱任务支配；110 语料与 32k 示教的质量/技能双重浪费；第 2 轮 loader 权重不生效（F11）需自行 patch。
- **本轮深化**：①示教按事件切 chunk，一份 chunk 同时用于训练采样与 I10 检索库（数据只处理一次，两处受益）；②族级加权：32 考题全量、孪生任务半权重、远任务 ≤5%；③质量加权：chunk 级质量分（进度效率 × 平滑度 × 成功裕度）进入训练权重与检索权重 \(q_i\)。
- **与现有方案差异**：别人把数据只当训练燃料；本点让同一份数据在训练期与推理期各变现一次。
- **技术可行性**：高（LoRA/frozen-VLM 单卡起步，F11）。
- **所需资源**：孪生子集 ≈1–2TB + 32 任务 ≈2TB；训练 1×24GB 起步、8×A100 上限；索引 2–4GB。
- **落地步骤**：①孪生表；②切 chunk 与质量打分；③loader patch + 频率单测；④共训；⑤族级 L0 消融后放量。
- **风险**：负迁移；chunk 切分边界质量差污染记忆库。缓解：家族级 L0、边界事件多信号投票、低权重起步。

### I1 v2 考纲校准五轴增广引擎 ★★★★★（维持）
- **动机**：计分的 320 次真机评测每次都在 5 轴上偏离训练分布，泛化缺口是全局乘性损失。
- **深化**：按手册/任务 wiki 的考纲卡采样增广参数；剂量-响应与轴间交互消融；本轮额外让增广器为 I10 的键对比学习提供 nuisance 正样本（背景/光照/干扰物/JPEG/resize），一份增广两用。
- **技术可行性**：高；1×24GB GPU。
- **落地步骤**：①32 张考纲卡；②背景/干扰物放量；③外观/位置 L0；④剂量定档；⑤轴间析因。
- **风险**：考纲卡偏差；位置重拼接物理不可行（>5% 不可行动作即降级）。

### I3 接触任务族关键点视觉伺服回退 ★★★★（维持）
- 通用 chunk 负责接近段、几何伺服负责接触段；`ee` 控制空间 + per-step 调用支持；关键点用开放词汇检测零训练起步。
- 本轮补充：I10 的接触段 chunk 记忆为伺服提供整段时序先验；降级预案 I3'：若混合推理被裁定违规，改为训练时辅助监督，推理纯端到端。

### I6 确定性低延迟部署 ★★★★（维持）
- 共享 backend + 端口隔离、fp8/INT8、torch.compile/CUDA Graph、obs 预取、断线重连 + 健康探针。
- 本轮补充：检索每 Δ 一次，p99 预算拆成「推理 + 检索」两部分；T_a=8、15Hz 时 Δ≈533ms，检索 <5ms 可忽略；T_a=1 时 Δ≈66ms，检索必须进 GPU 并缓存键。

### I7 世界模型测试时前瞻 ★★（缓）（维持）
- 高险节点 O(1–2) 次小 rollout 择优；若延迟余量不足即裁撤推理路径。
- 本轮重定位：WMA-0 更适合做 **chunk 续写器**——为 I5 合成恢复段、为 I10 增广稀有相位 chunk，而不是测试时在线前瞻。

### I8 v3 评测运营 + 分级消融注册表 ★★★★
- **L0 in-silico**：I1 各轴剂量；I2 孪生家族迁移；I9/I10 检索专项——precision@k、相位误差、边界 J、nuisance 翻车率、标称 Harm；I5 合成段质量。
- **L1 分数因子**：检索 on/off × 相位对齐 on/off × 边界代价 on/off × 门控 on/off（2^(4-1)）。
- **L2 真机**：只测 top 2–3；检索类候选必须先过 Harm≈0。
- **注册表**：记录「离线代理 → 真机增益」，滚动 Spearman；相关性 >0.6 才可单独准入 L2。
- **风险**：检索离线指标与真机相关建立慢；缓解：先用历史对齐点回填。

```python
def segment_episode(traj, min_len=8, max_len=32):
    # 边界多信号投票：夹爪开合跳变、末端速度极小、官方得分点达成帧
    cuts = merge_boundaries([0, len(traj)] + traj.gripper_events +
                            traj.velocity_minima + traj.scoring_hits, min_len)
    for a, b in windows(cuts, max_len):
        for s in range(a, b, max_len // 2):          # 50% overlap
            yield Chunk(
                key=embed_obs(traj.obs[s]),          # 指令+物体几何+本体
                actions=traj.actions[s:s + max_len],
                phase=s / len(traj),
                skill=traj.task,
                quality=progress_eff(traj) * smoothness(traj) * success_margin(traj),
            )
```

### 1.2 首 chunk 惰性检索 + 相位对齐 + 边界门控（I9 v2 / I10）

```python
class ChunkMemoryPolicy:                  # 唯一参赛实体：一个 PolicyService
    def reset(self):                      # F21：无观测，只清状态
        self.epi = []                     # 情景记忆：本集已执行 chunk 与结果
        self.initialized = False
        self.last_action = None

    def get_action(self, obs):
        if not self.initialized:          # F21：首帧只能在这里拿
            self._init_semantic(obs)      # I9：物体→技能/抓取先验
            self.initialized = True

        k, phi = self.key(obs)            # 指令 + DINOv2 物体几何 + 本体相位
        cand = self.index.search(k, k=8)
        cand = [c for c in cand
                if c.dist < TAU and abs(c.phase - phi) < DELTA]
        if cand:
            c = min(cand, key=lambda c: boundary_cost(c, self.last_action, self.recent))
            if not agree_with_vla(c, obs) or c.dist > TAU_STRICT:
                c = None                  # PR6：三条件不全满足则弃用
        a_vla = self.vla.propose_chunk(obs)
        g = self.gate(k, c) if c else 0.0
        a = g * warp(c.actions, c.phase, phi) + (1 - g) * a_vla
        a = self.epi_guard(a, obs)        # 避免重复本集已失败的 chunk
        a = self.tail_hold(a, uncertain=(c is None))   # I4：块尾收敛到安全姿态
        self.last_action = a[-1]
        return a

def boundary_cost(c, a_prev, recent):
    if a_prev is None:
        return 0.0
    a0 = warp(c.actions, c.phase, c.phase)[0]
    return (norm(a0 - a_prev, SIG)
            + LAM * norm((a0 - a_prev) - (recent[-1] - recent[-2]), SIG)
            + MU * dtw(c.actions, recent))
```

### 1.3 全局 T_a 扫描与检索放大效应（I4 v2 / Q9）

```python
def choose_global_Ta(policy, tasks, f_exec=15.0, L=1.2):
    rows = []
    for Ta in [1, 2, 4, 8, 16]:
        p99 = measure_p99(policy, Ta)             # 推理 + 检索
        react_ok = p99 < (Ta / f_exec) * 0.8      # 留 20% 余量
        score = l0_mixed_score(policy, tasks, Ta) # 接触/搬运各半
        tol = (L - 1) / (L ** Ta - 1)             # 检索误差容限（定义 1.3）
        rows.append((Ta, p99, react_ok, score, tol))
    return argmax_feasible(rows)                  # 检索开启后 tol 随 Ta 指数收紧
```

### 1.4 检索 L0 消融：先证不伤害，再证增益（I8 v3 / PR6）

```python
def retrieval_l0(policy, heldout, nuisance_axes):
    base = l0_score(policy, heldout)              # 检索关闭
    on   = l0_score(policy, heldout)              # 检索开启
    harm = mean(on[i] < base[i] for i in range(len(base)))
    flip = retrieval_flip_rate(policy, heldout, nuisance_axes)  # 同一状态检索结果是否翻车
    prec = precision_at_k(policy, heldout)        # 按技能+相位判对
    return {"harm": harm, "flip": flip, "prec": prec}
    # 准入：harm ≈ 0（<2%）且 prec 显著高于随机；否则回退纯 VLA
```

## 2. 实验设计（检索 × 分块联合协议）

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0-A | chunk 检索质量：precision@k、相位误差、边界 J vs 最近帧/均值/VLA-only | 离线（免费） | 边界 J 显著低于纯 VLA 拼接；相位误差 < 1 帧 |
| L0-B | 键不变性：背景/光照/干扰物/JPEG/resize 下检索翻车率 | 离线 | 翻车率 < 10%；同技能命中率 > 70% |
| L0-C | 标称 Harm：检索开/关在标称留出集上的分数差 | 离线 | Harm < 2%，否则禁用检索 |
| L0-D | 全局 T_a 扫描：{1,2,4,8,16} × p99 × 平滑度 × 接触/搬运代理分 | 离线 + 本地 stub | 选出唯一可行 T_a；检索开启后最优 T_a 不增大 |
| L1 | 2^(4-1)：检索 × 相位对齐 × 边界代价 × 门控 | 离线 + 少量真机 | 主效应显著的 ≤3 组合进 L2 |
| L2 | VLA-only vs +I9 vs +I10；PlugCharger/ZipUp/StoreCups 各 2 次 | 单任务通道 | 未见轴增益 > 0 且标称不降；边界 J 降 > 30% |
| 门禁 | PR4：run_client 全流程 + p99 + 动作健康度 | 本地 stub | 0 拒绝动作；p99 < T_a/f 的 80% |

**首批 L2 排队**：①I10 检索 Harm/增益（3 任务）→ ②I4 全局 T_a 确认 → ③I5 检索式恢复 → ④I2 孪生共训。
