### 第 1 轮灵感驱动研究记录（新循环 · 承接第 6 轮 CADVS-v6）

**灵感词**：多机协同、多轮对话

**继承关系**：第 6 轮 CADVS-v6（IP-497~500）在「七硬门不增」前提下，用 GGC/MCTM/STM 把单机的几何、空间、语义先验注入提议器，并用 η_g·η_topo·η_interp·η_cmd 软因子链只收紧、不放松证书边界。本轮继续「硬门不增」，把对象从「单机单轮」扩展到「N 机协同 × T 轮对话」：核心问题变为——当提议器同时为 N 个机器人生成联合计划、且指令来自一段带承诺历史的对话时，如何仍只用原来七道硬门完成认证。

**直觉与动机**：

1. **多机协同 → 从「联合求解」到「证书折叠」**。直觉上，N 机联合规划会诱使我们去增加一道「机间无碰撞」硬门；但这会破坏「硬门不增」。反过来想：碰撞是**对称关系**，只要把已承诺的邻机轨迹当作「随时间变化的虚拟障碍」，注入每个机器人原本就有的 BCK/VACK 碰撞检查，则后提交的机器人必然看见先提交者。于是联合证书 = N 份单机证书的合取，**机间约束不新增门，而是折叠进已有门**。关键洞见：**安全可以被串行化，而不必被集中化**。

2. **多机协同 → 从「集中分配」到「契约 + 预约」**。谁来做什么、谁先走，是协同的第二层问题。引入「协同契约分解」（CCD）：用市场/拍卖把联合指令拆成带所有权与截止期的子任务契约；再用「时空预约折叠」（SRF）以固定优先级 + 两阶段提交把冲突串行化。关键洞见：**把全局一致性降维成「一份无冲突的时空预约表」**，而预约表只作为条件与虚拟障碍进入现有流水线。

3. **多轮对话 → 从「单句语义」到「承诺状态」**。v6 的 STM 只把当前句 L 映射为 q_L；但「不要动红色的」之后再说「把它放左边」中的「它」和否定约束，必须跨轮继承。引入「对话承诺状态机」（DCSM）：显式维护承诺集合 C_t（对象、谓词、期限、状态），把查询变成历史条件 q_t = STM(H_t, C_t)，并在检测到矛盾/撤销时**先反问、不执行**。关键洞见：**多轮的正确性不是「每句都对」，而是「承诺集合不矛盾且单调」**。

**关键洞见**：v5 回答「提议=任意生成器时边界如何不变」；v6 回答「单机下如何让提议符合物理/空间/意图」；v7 回答「当生成器是 N 个耦合智能体、指令是 T 轮承诺历史时，如何仍不新增硬门」。七硬门 kc_evidence_forged_v5 原样复用；本轮新增的只有：
- IP-501 CCD（协同契约分解），
- IP-502 SRF（时空预约折叠），
- IP-503 DCSM（多轮承诺状态机），
- IP-504 EFA-v7（协同/承诺软因子链）。

**形式化目标（增量）**：

1. **CCD（Collaborative Contract Decomposer）**：<br>
   - 输入：历史条件查询 q_t、机器人集合 R={1..N}、能力/位置上下文；<br>
   - 输出：契约集合 K = {(r, φ_r, ρ_r, d_r, owner_r)}，φ_r 为子任务谓词，ρ_r 为目标，d_r 为截止期，owner_r 为所有权；<br>
   - 分配：最小化 Σ_r c_r(φ_r) s.t. 能力可行 cap(r,φ_r)=1、覆盖 ∪_r φ_r ⊇ φ(L)；用拍卖/匈牙利近似；<br>
   - 所有权清晰度 owner_clarity ∈ [0,1] 进入软因子。

2. **SRF（Spatiotemporal Reservation Folding）**：<br>
   - 优先级 π：固定全序（令牌/领导者选举产生，运行期不变）；<br>
   - 预约表 RT: (cell, t_bucket) ↦ r，t_bucket 为离散时间桶；<br>
   - 折叠算子 Fold_r(x^(r)) = 把 {x^(π(j)) : j<k} 在 t 时刻占据体素作为虚拟障碍 O_{<k}(t) 注入既有 BCK；<br>
   - 两阶段提交：tentative-reserve → all-ack → commit；超时 abort 并退避/回退；<br>
   - 共识度 cons_coop ∈ [0,1] 进入软因子。

3. **DCSM（Dialogue Commitment State Machine）**：<br>
   - 状态 C_t = {c_1..c_m}，c=(agent, predicate, object, deadline, status)；<br>
   - 更新 Δ_t = Parse(L_t)，C_{t+1} = Apply(C_t, Δ_t)；<br>
   - 矛盾检测 contra(C_{t+1})=1 若存在 c_i, c_j 语义互斥（如 move 与 ¬move 同一对象同一时段）；<br>
   - 一致性 cons_turn = 1 − |矛盾|/|C|，η_turn = 1 + λ_turn(1−cons_turn)；<br>
   - 若 contra=1 → 返回 CLARIFY_REQUEST（反问），不进入执行。

4. **EFA-v7 软评分**：ECS_v7 = ECS_v6 · η_coop · η_turn · η_owner，其中 η_* = 1 + λ_*(1−cons_*) ∈ [1,1+λ_*]，λ_* 使 Π ≤ 1.3；任何 cons_* 低于阈值 θ_coop/θ_turn → 直接回退 v6 单机规则提议。

5. **形式化定义**：给定对话历史 H_t=(L_1..L_t)、机器人集 R、记忆 M：<br>
   - C_t = DCSM(H_t)；若 contra(C_t)=1 → CLARIFY_REQUEST；<br>
   - q_t = STM(H_t, C_t)；<br>
   - K = CCD(q_t, R, ctx)；<br>
   - ∀r: cands_r = FMPP.propose(c_ctx^{(r)}, K=8)；<br>
   - X = SRF.commit({cands_r}, π, T_timeout)；<br>
   - Exec_CADVS-v7 = {X : ∀r ∧_i kc_i(x^{(r)}, O_{<k}; τ_i^{v7})=1}，其中 τ_i^{v7} = γ_i·τ_i^{v5}·Π_factor_i^{v6}·η_coop·η_turn·η_owner。

**本轮最大风险**：**全局协同承诺的一致性无法被局部证书覆盖**——每台机器人、每一轮对话都可局部合规，但跨机跨轮的活锁、承诺违约与指代漂移在结构上游离于七硬门与单轮语义映射之外。

## 2. 关键算法骨架

### IP-501 CCD：协同契约分解

```python
@dataclass
class CollaborativeContractDecomposer:
    """CCD：联合指令 → 带所有权/截止期的单机契约。
    红线：契约只作条件与分配依据，不参与梯度，不改动任何硬门。"""
    deadline_slack: float = 1.2
    lambda_owner: float = 0.1

    def decompose(self, q_t, robots, ctx) -> list[Contract]:
        """从历史查询展开子目标，拍卖式最小成本覆盖分配"""
        subgoals = self._expand(q_t, ctx)                 # 由承诺条件展开 φ(L)
        bids = {}
        for r in robots:
            for phi in subgoals:
                if cap(r, phi):
                    bids[(r, phi)] = self._bid_cost(r, phi, ctx)
        assign = hungarian_min_cost(bids, cover=subgoals)  # 覆盖约束 ∪φ_r ⊇ φ(L)
        contracts = []
        for (r, phi) in assign:
            contracts.append(Contract(
                robot=r, phi=phi, rho=self._target(phi),
                deadline=self._deadline(phi, ctx),
                owner=self._owner(phi, ctx)))
        return contracts

    def ownership_clarity(self, contracts) -> float:
        """所有权冲突越少越清晰：1 − 冲突对数/总对数"""
        conflicts = count_overlapping_owners(contracts)
        total = max(len(contracts) * (len(contracts) - 1) / 2, 1)
        return max(0.0, 1.0 - conflicts / total)
```

### IP-502 SRF：时空预约折叠

```python
@dataclass
class SpatiotemporalReservationFolding:
    """SRF：固定优先级 + 时空预约 + 两阶段提交。
    邻机已承诺轨迹折叠为虚拟障碍 O_{<k}(t)，注入既有 BCK/VACK。
    红线：不新增硬门；预约只改变碰撞检查的输入，不改变检查本身。"""
    order: list[int]                 # 固定全序 π（令牌选举产生）
    rt: ReservationTable             # (cell, t_bucket) -> robot
    timeout_ms: float = 50.0
    t_bucket: float = 0.05
    lambda_coop: float = 0.1

    def fold_and_commit(self, cands_by_robot, v6) -> tuple[JointPlan | None, dict]:
        """逐机串行提交；返回联合计划与每机证书结果"""
        committed, certs = {}, {}
        for r in self.order:
            best = None
            for x in cands_by_robot[r]:
                obstacles = self._virtual_obstacles(committed)   # O_{<k}(t)
                if not self._reserve_tentative(r, x):             # 预约冲突 → 跳过
                    continue
                ok, cert = self._passes_v6_gates(x, obstacles, v6)  # 复用七硬门+BCK
                if ok:
                    best, certs[r] = x, cert
                    break
                self._release(r, x)
            if best is None:
                self._abort_all(committed)                        # 两阶段提交失败
                return None, {}
            committed[r] = best
        self._commit_all(committed)                               # all-ack → commit
        return JointPlan(committed), certs

    def consensus(self, plan) -> float:
        """共识度：成功提交比例，并惩罚重试次数"""
        return len(plan.agents) / plan.N * (1.0 / (1.0 + plan.retries))
```

### IP-503 DCSM：多轮承诺状态机

```python
@dataclass
class DialogueCommitmentStateMachine:
    """DCSM：跨轮承诺集合 C_t 的更新、撤销与矛盾检测。
    矛盾即反问，不执行——把「多轮正确」定义为承诺集不矛盾。"""
    lambda_turn: float = 0.1
    theta_turn: float = 0.6

    def update(self, C_prev: set[Commitment], L_t: str) -> tuple[set, float]:
        """解析本轮更新并做矛盾检测；返回 (C_new, cons_turn)"""
        delta = self.parser(L_t)                     # add/modify/revoke
        C_new = apply_delta(C_prev, delta)           # 无显式 revoke 时只增
        contra = self._contradictions(C_new)
        if contra:
            return C_new, 0.0                        # 触发 CLARIFY_REQUEST
        cons = 1.0 - len(contra) / max(len(C_new), 1)
        return C_new, cons

    def _contradictions(self, C) -> list[tuple]:
        """语义互斥检测：同一 (object,time) 上 move/¬move、pick/place 冲突等"""
        out = []
        for a, b in combinations(C, 2):
            if mutually_exclusive(a, b):
                out.append((a, b))
        return out

    def eta_turn(self, cons: float) -> float:
        return 1.0 + self.lambda_turn * (1.0 - cons)   # ∈ [1, 1+λ_turn]
```

### IP-504 EFA-v7：七硬门 + 协同/承诺软因子链

```python
@dataclass
class EvidenceForgingAssemblerV7:
    """EFA-v7：七硬门不变 + 协同/承诺软因子链。
    承诺矛盾 → 反问；协同/承诺一致性低于阈值 → 回退 v6 单机。"""
    ccd: CollaborativeContractDecomposer
    srf: SpatiotemporalReservationFolding
    dcs m: DialogueCommitmentStateMachine
    stm: SemanticTrajectoryMapper
    v6: EvidenceForgingAssemblerV6
    theta_coop: float = 0.6
    theta_turn: float = 0.6

    def select(self, H_t, t_now, context, robots):
        # 1. 承诺状态：矛盾短路，低一致回退
        C_t, cons_turn = self.dcs m.update(context.C_prev, H_t[-1])
        if cons_turn == 0.0:
            return CLARIFY_REQUEST, None, 'COMMITMENT_CONTRADICTION'
        if cons_turn < self.theta_turn:
            return self.v6.select(H_t[-1], t_now, context)     # 回退单机 v6
        q_t = self.stm.forward(H_t, C_t)
        eta_turn = self.dcs m.eta_turn(cons_turn)

        # 2. 契约分解
        contracts = self.ccd.decompose(q_t, robots, context)
        eta_owner = 1.0 + self.ccd.lambda_owner * (
            1.0 - self.ccd.ownership_clarity(contracts))

        # 3. 逐机提议（共享条件，独立候选）
        cands = {}
        for r in robots:
            c_ctx_r = build_ctx(context, contracts, q_t, C_t, r)
            cands[r] = self.v6.fmpp.propose(c_ctx_r, K=8)

        # 4. 预约折叠 + 两阶段提交（七硬门在此逐机执行）
        plan, certs = self.srf.fold_and_commit(cands, self.v6)
        if plan is None:
            return self.v6.select(H_t[-1], t_now, context)     # 提交失败 → 回退单机
        cons_coop = self.srf.consensus(plan)
        if cons_coop < self.theta_coop:
            return self.v6.select(H_t[-1], t_now, context)
        eta_coop = 1.0 + self.srf.lambda_coop * (1.0 - cons_coop)

        # 5. 汇总逐机证书（虚拟障碍已在折叠时注入，此处不重复判定）
        if not all(certs.values()):
            return False, None, 'HARD_GATE_REJECTED'
        return True, plan, 'FORGED_CGE_V7'

    def ecs_v7(self, plan, eta) -> float:
        """ECS_v7 = ECS_v6 · η_coop · η_turn · η_owner"""
        return self.v6.ecs_v6(plan, eta) \
               * eta['coop'] * eta['turn'] * eta['owner']
```

### 集成流水线（v6 → v7）

```
离线/慢时域：
  DCSM 解析器与矛盾规则库（小时级，人工校验）
  CCD 能力表与拍卖权重校准（小时级）
  SRF 优先级策略与超时参数（分钟级）
  v6 的 GGC/MCTM/STM 权重继续复用，不重训

在线会话层（秒级）：
  H_t ──▶ DCSM.update ──▶ C_t（矛盾 → CLARIFY_REQUEST 反问）
                     └──▶ q_t = STM(H_t, C_t)
  q_t ──▶ CCD.decompose ──▶ 契约 K + η_owner
  K,q_t ──▶ 每机 FMPP.propose ──▶ cands_r
  cands_r ──▶ SRF.fold_and_commit（固定 π，两阶段提交）
        ├─ 提交失败/超时 ──▶ 回退 v6 单机规则提议
        └─ 提交成功 ──▶ 逐机七硬门（虚拟障碍已注入）──▶ JointPlan
  软因子 η_coop·η_turn·η_owner 只收紧阈值；任一低于阈值即回退

在线控制环（< 0.6 ms/机）：
  折叠与预约在准入时域完成；控制环只消费已提交轨迹与既有 v6 缓存
```

|---|---|---|---|---|
| CCD.decompose | O(N·|Φ|·log(N·|Φ|))（匈牙利近似） | O(N·|Φ|) | N≤16, |Φ|≤8 | < 5 ms（准入） |
| SRF.reserve | O(|x|/t_bucket · cells) | O(N·cells·buckets) | t_bucket=0.05 | < 1 ms/机 |
| SRF.fold_and_commit | O(N·K·gate) | O(N·|x|) | K=8 | < 10 ms（N=8） |
| DCSM.update | O(|C|²) 矛盾两两检测 | O(|C|) | |C|≤32 | < 0.2 ms |
| STM(H_t,C_t) | O(T·L·d_model) | O(T·d_query) | T≤10, L≤50 | ~2 ms（端侧） |
| EFA-v7 汇总 | O(N) | O(N) | — | < 0.05 ms |
| 通信/决策 | O(N·|π|·cells) | — | 仅共享预约摘要 | ~4 KB |

**端到端在线增量**：会话层与折叠在准入时域完成（~10 ms 量级，N=8），控制环只消费已提交结果，维持 v6 的 < 0.6 ms/机目标；协同开销随 N 线性增长，但均不进入硬实时控制回路。

## 4. 正确性论证（增量更新）

### 定理 11（证书折叠的可靠性 / Soundness of Certificate Folding）

**陈述**：固定全序 π，SRF 对每机注入虚拟障碍 O_{<k}(t)。若所有 N 份逐机证书通过，则联合计划 X 两两时空无碰，且未新增任何硬门；对同一轨迹，Exec_v7 ⊆ Exec_v6 ⊆ Exec_v5。

**证明**：对提交序归纳。任取一对 (i,j)，设 π^{-1}(i)<π^{-1}(j)，则 j 提交时 i 的轨迹已折叠入 O_{<j}；j 的碰撞门通过 ⇒ 二者在任意 t_bucket 不共占体素。碰撞关系对称，故 (i,j) 无碰。硬门集合与 v6 完全相同，唯一变化是 BCK 输入多了虚拟障碍，因此是对原门的单调收紧（执行集只会缩小）。软因子 η_* ≥ 1 只升高阈值 τ_i^{v7}，同样只收紧。∎

### 定理 12（承诺单调性与无静默违约）

**陈述**：若无显式撤销，则 C_t ⊆ C_{t+1}；且当 contra(C_t)=1 时系统返回 CLARIFY_REQUEST 而不执行。因此不存在「未澄清即违背既有承诺」的静默违约路径；但指代/解析漏检会使承诺集本身出错。

**证明**：Apply 只在显式 revoke 时删元素，否则只增，故单调。contra 检查位于执行前短路，矛盾态直接进入反问出口。漏检属于解析器召回问题，不在状态机保证范围内（见诚实声明）。∎

### 定理 13（安全—活性分离）

**陈述**：在固定 π 与有限超时下，SRF 不产生循环等待（安全）；但可能因反复 abort 出现饥饿（活性仅概率保证），故以回退 v6 单机作为活性兜底。

**证明**：等待关系沿 π 单向——每机只等待更早提交者，π 无环 ⇒ 无循环等待；超时终止等待。反复 abort 不违反安全，但可能长期不提交，回退路径保证系统仍能前进。∎

### 诚实声明

- 折叠依赖跨机时钟同步与低延迟通信；时钟偏斜会让「同一 t_bucket」判定失真，定理 11 的前提被破坏；
- 动态障碍 + 陈旧预约可导致折叠失效（先提交者未预见后出现的障碍）；
- DCSM 矛盾检测依赖解析召回，漏检即静默违约，状态机本身无法兜底；
- 软因子 ≥ 1 仅收紧阈值，但全局活性（livelock/饥饿）无法由任何局部证书保证；
- 历史条件 STM 存在近因偏置，早期承诺可能被近期轮次稀释；
- N 机联合的通信与协调开销随 N 增长，规模上限需实测，不能从单机 P99 外推。

## 7. 本轮最大风险（最终确认）

**一句话**：**全局协同承诺的一致性无法被局部证书覆盖**——每台机器人与每一轮对话都可局部合规，但跨机跨轮的活锁、承诺违约与指代漂移在结构上游离于七硬门与单轮语义映射之外。
