# 第 8 轮（灵感循环 R3）· SAVE：多机器人不是队友，是多视角；跨任务是共享物体槽；视觉编码器要输出米制工作区

> 检索/复核日期：**2026-10-25（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「多机器人协作」「跨任务泛化」「视觉编码器」。我先说一个会得罪字面解读、但能省掉两周弯路的判断：**UniBot 没有多机器人协作任务。** 32 个任务都是单台 G1、单模型、桌面操作；评测里的多台机器人是并行载体，不是需要互相通信的队友。字面去做 multi-robot，既没有评测信号，也会违反“单模型 + 单机任务”的形态。真正可做的翻译是：把 **四路相机当成一个“多视角团队”**，把 **双臂当成一个“双代理团队”**，把 **跨任务** 当成共享的物体/技能槽，把 **视觉编码器** 从“语义 token 提取器”改成 **机器人基座系里的米制物体工作区**。一句话主判断：**预览榜的 30% 上限不是真实天花板，但五类泛化轴全是感知分布偏移；与其换更大的 VLA，不如把四路 RGB + 本体位姿压成一块持续更新的 3D 物体工作区，让位置、干扰物、背景、未见物品四个轴同时受益，再用 episode 级物体记忆补人为干扰轴。**

## 0. 先校正三个会误导整轮的事实

### 0.1 公开榜单仍是占位，29.7% 不能当真实 SOTA

榜单页现在能渲染 8 条记录：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。但 `leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，详情页视频仍是“测试视频占位”，页面仍标“即将发布”[S3][S4]。所以：

- **真实排名、轴级瓶颈、头部方案强弱，全部未知**；
- 29.7% 只能当“早期预览的难度先验”，不能用来证明“30% 是天花板”，更不能用来反推“头部用了什么”；
- 本轮不再基于占位榜做任何“补最弱轴/挑最高分任务”的分配，只用官方任务结构、数据和我自己读到的 parquet/JSON 做判断。

### 0.2 排名是成功率优先，步骤分只是 tie-break（第 7 轮需修正）

官方手册明确：32 个任务每个跑 10 次，5 类泛化各 2 次，共 **320 次计分运行**；单次最多 **180 秒**；实时榜按 **32 任务总平均成功率** 排序，成功率相同才看总平均步骤分，再相同看提交日期[S1][S2]。

这修正了第 7 轮把“成功率与步骤分综合排序”当目标函数的错误。**步骤分是诊断信号和 tie-break，不是第二目标。** 终局放置仍然是成功闸门（成功=所有步骤完成），但“终局放置占 ~60% 步骤分”不能直接换算成排名增益；任何只提高部分步骤、不提高整条任务成功率的改进，对排名的期望增益接近 0。本轮所有设计都以“整条任务成功率”为唯一主目标。

### 0.3 “多机器人协作”在正赛里没有对应任务，必须翻译

官方 32 个任务都是单台 G1 的桌面操作；评测用多台机器人是为了并行和泛化，不是让机器人互相传球。提交接口也没有机器人间通信、队友观测或共享动作的字段[S5][S6]。所以字面做 multi-robot 会变成“自嗨 demo”，无法被 320 次计分运行检验。

本轮把它翻译成三件可检验的事：

1. **多视角团队**：head stereo left/right + wrist left/right 是四个“视角代理”，它们对同一个物体槽投票；分歧=遮挡/反光/干扰，而不是噪声。
2. **双臂团队**：左右臂是两个“执行代理”，用 role token（hold / manipulate / handover / bimanual-lift）协调；这对应 PackBag/OrganizePencilCase 这类双手任务。
3. **跨具身团队（可选，默认关闭）**：CHORUS 证明一个共享 VLA backbone 可以控制不同机器人团队，但 UniBot 没有机器人间协作任务；我们只借“共享策略、局部观测”的原则，不引入机器人间通信，也不把外部机器人数据当主粮[S16]。

一句话：**在 UniBot 里，multi-robot 的正确读法是 multi-view + multi-arm，而不是 multi-agent communication。**

## 1. 本轮核实到的五个硬事实

### 1.1 数据已经全量落地，而且带双目标定

HF collection 实测 32 个数据集、**33,276 条 episode、18,282,246 帧、30fps 下 169.3 小时**；每个任务 969–1,533 条，全部 `lastModified` 在 2026-10-14 前后[S7]。HangCup 为 1,043 条 / 194,564 帧，episode 中位数 177 帧 ≈ 5.9 秒[S8]。

更重要的是 `meta/info.json` 里的 `camera_params`：

```text
head_stereo.rectified = true
T = (-58.2526, -0.1675, 0.5786)   # 毫米级基线，约 58.25 mm
K_left  = [282.369, 0, 311.525; 0, 282.752, 256.628; 0, 0, 1]
K_right = [281.874, 0, 329.958; 0, 282.319, 249.512; 0, 0, 1]
```

也就是说，**官方训练数据里存在一对已标定、近似水平、约 58 mm 基线的头戴双目**。这是本轮最重要的“便宜杠杆”：如果评测的 `cam_left_high` / `cam_right_high` 就是同一对相机，我们就能从两张 RGB 恢复米制深度；而提交 API 本身**不提供 depth、不提供相机外参**，这正好是别人没吃到的信息[S6][S8]。

必须诚实：`rectified=true` 但左右 `cx` 相差约 18 px，不能盲信“已经完全对齐”；评测相机是否同型号/同基线/同分辨率也未确认。这个杠杆必须先用不计分单任务调试槽做极线/平面/尺度自检，不能直接写进主路径。

### 1.2 32 任务、94 步、3200 分，技能词汇高度复用

32 个任务的 `score_steps` 合计 94 个评分步骤、3200 分[S9]。对步骤文本做粗略关键词统计：`Grab` 19 次、`Place` 15 次、`Put` 10 次、`Pick` 6 次——**四个动词覆盖约 50/94 步（53%）**；其余是 Open/Close/Zip/Fold/Pour/Plug/Stack 等。这说明：

- 32 个任务不是 32 个互不相干的技能，而是 **“抓—运—放/插/合/倒”这组共享技能 + 不同物体/容器/关系** 的组合；
- 跨任务泛化最合理的归纳偏置不是“每任务一个头”，而是 **共享的物体关系槽 + 共享的技能槽**；
- 这也解释了为什么单纯堆任务数据会互相干扰：如果表征不共享，32 个任务的梯度只是在抢容量。

### 1.3 五类泛化轴各占 20%，其中四类是视觉分布偏移

手册的 5 类泛化是位置、干扰物、桌面背景、未见物品、人为干扰，每类 2/10 次，即各占 **20%**。前四类本质都是“视觉观测分布变了，但任务语义没变”；第五类是“场景状态在 episode 中变了”。这给了一个很干净的杠杆表：

| 轴 | 失败机制 | 表征层对策 | 现实增益假设 |
|---|---|---|---|
| 位置 | 单目尺度/相机坐标 | 双目米制 + 基座系工作区 | +5–8pp |
| 干扰物 | 物体/背景特征纠缠 | object slots + 关系 token | +4–6pp |
| 背景 | 纹理 shortcut | 规范化的俯视工作区 | +5–8pp |
| 未见物品 | 语义/形状 OOD | DINOv3 dense + 槽形状/几何 | +4–7pp |
| 人为干扰 | 状态突变、无记忆 | episode 级物体记忆 + 恢复 | 该轴 +5–10pp |

如果前四轴各 +4–6pp、人为干扰轴 +5–10pp，**总成功率约 +3.6–5.8pp**。这不是“翻倍”，但在 320 次评测、SE≈2.6pp 的尺度上已经是可感知的增益；而且它不依赖某个任务的特殊技巧。

### 1.4 视觉编码器的证据链已经足够强，缺的是“米制 + 持久”

2026 年的证据不再支持“视觉编码器随便换个更大的就行”，而是指向三个具体结论：

- **通用视觉表征比任务特定表征更稳**：R2-WAM 系统比较后认为，强通用视觉表征带来的鲁棒性收益最大，额外模态/来源并不总是可加[S17]；DEM 用 fine-tuned DINOv3 + frozen language + MeanFlow head，在 18 个 RoboCasa 任务上做到 55.6%，与 GR00T N1.7 的 56.9%、π0.5 的 54.6% 接近，但单次前向只要 6.1ms[S18]。这说明“视觉编码器 + 轻动作头”可以在保持竞争力的同时大幅降延迟。
- **双目几何是真实的精度杠杆**：StereoVLA 的 GeoSem 编码器在真机报告 +33.4% 绝对成功率，并对近半球视角变化更稳[S12]；ExStereo 用 stereo 模块 + action-stereo cross-attention 把 π0.5/SmolVLA 提升，并在双臂 PiPER 上验证[S13]；StereoPatch 在其实验里报告 stereo 89.2% vs D435 73.0% vs D405 51.4%[S14]。这些结果共同说明：**显式度量几何不是“锦上添花”，在精密放置/插入上是主变量。**
- **物体中心/关系中心表征适合多任务**：SlotVLA 用 slot-attention 同时建模物体和关系，显著减少视觉 token，并保持竞争性泛化[S10]；OC-VLA++ 用 paired-view 监督和 cross-view action equivariance 提升未见视角泛化[S11]。它们缺的正是“米制尺度 + 机器人基座锚定 + episode 记忆”。

### 1.5 记忆文献很多，但 UniBot 不需要“长期记忆”，需要“短时状态突变检测”

MemoryVLA、Chameleon、MemBodied、EvoMem-VLA 等都在做长程/情景记忆[S20][S21][S22][S23]。但 UniBot 的 HangCup episode 中位数只有 5.9 秒，32 个任务也大多是 2–5 步；把整套长时记忆搬进来，参数和延迟都不划算。

官方 human 备注恰好给出了更窄的需求：T27「叠了第二个之后拿下第二个」、T19「拉上保险之后拉开」、T10「将插头拔起」[S9]。这些不是“回忆十分钟前的房间”，而是 **1–3 秒内物体槽的位置/存在性/关系被外部改变**。所以本轮只做 **ELM（Episodic Latent Memory）**：最近 1–2 秒的物体槽轨迹 + 恒速预测 + 突变检测；检测到“物体被移动/拿走/关系被撤销”就触发重定位/回退，而不是存一个长视频库。

## 2. 三个灵感词，各自钉到可执行杠杆

### 2.1 多机器人协作 → 多视角共识 + 双臂角色

- **多视角共识**：head stereo 提供全局米制点云，wrist 两路提供局部高分辨率；四路都投影到同一个基座系/桌面系物体槽。若某物体在 head 与 wrist 的槽位置不一致，分歧度作为“遮挡/反光/被移动”的置信度，而不是直接平均。
- **双臂角色**：从演示里挖 role 时间线——左手先闭合且保持=`hold`，右手闭合且移动=`manipulate`，两手都闭合后一手松开=`handover`，两手一起抬=`bimanual-lift`。role token 由语言 + 当前步骤 + 物体槽预测，条件到同一个 action expert；不新增策略。
- **不做的事**：不做机器人间通信、不做集中式多机规划、不把 CHORUS 的多机数据当主粮。我们只借“共享 backbone、局部观测”的原则，把它落在单机的多相机/双臂上。

### 2.2 跨任务泛化 → 共享物体关系槽 + 共享技能槽

32 个任务共享 50/94 个 Grab/Place/Put/Pick 步骤，这意味着跨任务的关键不是“记住 32 个任务”，而是：

1. **物体关系槽**：每个槽带 `μ, Σ, extent, color, semantic embedding` 和关系 `r_ij`（距离、上下、内外、接触）。同一套槽接口服务抓取、放置、插入、闭合、倾倒。
2. **技能槽**：reach / grasp / lift / transport / place / insert / press / close / open / pour / fold / zip / handover。路由器根据语言 + 当前步骤 + 物体关系选择 soft skill token，条件到 action expert。
3. **任务无关的验证**：SSG 的步骤谓词直接定义在物体关系上（如“bowl2 on bowl1”“plug in strip”“zipper closed”），而不是任务特定的分类头。

这样“跨任务”不是靠 32 个 LoRA/32 个 head，而是靠 **共享槽 + 轻路由**；最终仍然是一个 checkpoint，符合单模型规则。

### 2.3 视觉编码器 → 不是语义 token，是米制物体工作区

现有 VLA 的视觉塔大多输出 2D patch tokens：语义强、尺度弱、背景纠缠。UniBot 需要的不是再叠一个 SigLIP，而是把视觉输出改成三层：

1. **米制几何层**：head stereo → 视差 → 深度 → 头系点云 → 桌面系/基座系点云；用桌面平面 + 双 EE 位置解一个 table-anchored frame（TAF），不需要评测给外参。
2. **物体槽层**：class-agnostic slot head（从 SAM2/跟踪蒸馏，不在线上跑大模型）输出物体槽、容器槽、工具槽；每个槽有 3D 质心、协方差、朝向、可见性、关系。
3. **规范工作区层**：把槽渲染成 256×256 的俯视工作区图（高度、object ID、语义色、记忆残影、双 EE、目标锚点），作为 action expert 的“地图输入”。这张图与相机视角、背景纹理、物体外观解耦，直接对位置/背景/干扰物轴。

这就是 **SAVE（Stereo-Anchored Visual Environment）**：视觉编码器的输出不是“更像语言的 token”，而是“机器人能直接用于操作的一块米制工作区”。

## 3. 本轮主判断：瓶颈在表征，不在策略容量

### 3.1 一个更锋利的失败模型

| # | 失败模式 | 证据 | 对策 |
|---|---|---|---|
| V1 | 单目尺度/相机坐标错，抓取/放置偏几厘米 | API 无 depth/外参；StereoVLA/ExStereo/StereoPatch 均显示几何是主变量 | SAVE 双目 + TAF |
| V2 | 背景/桌面纹理 shortcut，换桌布就崩 | 五轴里有背景轴；SlotVLA/OC-VLA++ 说明物体/关系表征更稳 | 规范工作区 + 物体槽 |
| V3 | 相似物体/容器身份混淆，抓错/放错 | 32 任务里大量同色杯/碗/盘/工具；纯 2D token 易纠缠 | object ID + 关系槽 |
| V4 | 人把物体移走/撤销一步，模型继续执行旧计划 | 官方 human 备注全是“平移/撤销” | ELM 突变检测 + SSG 回退 |
| V5 | 双手任务用错手/不扶稳 | PackBag 等双手数据占比高；ACG-Bench 显示 arm-wise 结构关键 | A2A role token |
| V6 | 32 任务共享策略互相干扰 | 任务多、数据不均、技能重叠 | 共享技能槽 + 轻路由，而非每任务头 |

### 3.2 为什么不是“再训一个更大的 VLA”

- 官方数据只有 33k；更大的 VLA 可能把成功演示拟合得更好，但不会自动获得米制尺度、物体持久性、双臂角色。
- R2-WAM/DEM 的结果说明：**强通用视觉表征 + 合适的融合方式** 比“更大的 VLM”更划算；额外视觉来源也不是无脑叠加[S17][S18]。
- UniBot 的评分是成功率优先，失败集中在“没抓住/放不准/被干扰后不恢复”；这些是表征和闭环问题，不是语言推理问题。
- 单模型规则下，增加一个任务特定头/模型风险高；SAVE 是共享表征，不是第二个策略。

### 3.3 为什么现在做

- 官方数据 2026-10-14 全量落地，且带 stereo 标定；再晚数据可能变，但相机结构不会变。
- 公开榜仍是占位，真实排名没发布；现在做“别人没吃的几何信息”比猜头部方案更有信息优势。
- WLA-1.0-Base 已开源（6B、Apache-2.0、单卡 24GB 可微调），SAVE 可以直接挂在官方底座上，不需要从零预训练[S19]。
- 不计分单任务调试槽可以做 T01/T10/T19/T27/T18 的配对 A/B，足够验证核心假设[S24]。

## 4. 方案轮廓：SAVE-GPR

```text
语言(5 复述之一) ──► SSG 评分步骤图 ──► 当前步骤 s、技能先验
                                      │
head stereo L/R ──► 视差/深度 ──► 头系点云 ──► TAF 桌面系 ──┐
wrist L/R ──► DINOv3 dense ──► 局部物体槽 ──────────────────┤
proprio（双臂关节/EE/夹爪/腰）──► 基座系锚点 ───────────────┤
                                                          ▼
                                              SAVE 物体工作区
                                    ┌─────────┼──────────┐
                                    ▼         ▼          ▼
                              object slots  俯视工作区图  relation tokens
                                    │         │          │
                                    └────► ELM 短时记忆 ◄┘
                                           │ 突变/撤销检测
                                           ▼
                                    SSR 技能槽路由
                                           │
                                    A2A 双臂角色（可选）
                                           │
                     WLA-1.0-Base / GPR-VLA（单一 checkpoint）
                     VLM 语义 token + SAVE 几何 token + 工作区图
                                           │
                                    Action Expert → chunk
                                           │
                     SSG/PGL/OPT/SVL 闭环：谓词、锚点、位姿、落点验证
```

**最小可运行版（不重训）**：只把 SAVE 工作区图/物体槽作为额外观测，冻住 WLA，只训一个小 projector + action expert LoRA；先在 T27/T10 调试槽验证“模型会不会用这张图”。如果不会用，再进入全量 SAVE token 训练，而不是一上来重训 6B。

## 5. 与第 7 轮的关系：保留闭环，换掉输入表征

- **保留**：SSG 评分步骤图、PGL 放置目标阶梯、OPT 放置位姿迁移、SVL 落点 settle-verify、ICR 检索、NRB 官方备注恢复、DebugLoop。
- **升级**：SSG 谓词从“图像分类”改成“物体关系谓词”；PGL/OPT 的容器位姿从 2D 检测改成 SAVE 的 6D 槽；SVL 的稳定性检测从像素差分改成物体槽位移；ICR 的 key 从全局外观改成物体关系 + 运动。
- **新增**：SAVE 双目物体工作区、TAF 桌面锚定、ELM 短时记忆、SSR 技能槽路由、A2A 双臂角色。
- **修剪**：FLEET 第六轴、每任务 LoRA/专家、全 32 任务高保真孪生、自由仿真数据、运行时仿真/MPC、把步骤分当第二目标、基于占位榜的“头部方案”推断。
- **明确不做**：字面多机器人协作、机器人间通信、外部机器人数据（默认 OFF，规则确认后再议）。

## 6. 可证伪的假设与预期增益

| # | 假设 | 检验 | 杀停线 |
|---|---|---|---|
| H1 | 双目 + TAF 比 RGB-only 在位置/背景/未见物品轴上更稳 | 8 任务 object/background held-out + T27/T10 canary | 三轴平均 < +3pp 或深度误差 > 2cm → 关 SAVE 几何，只留工作区图 |
| H2 | ELM 能在 1–3 秒内检测物体被移动/撤销，并触发正确回退 | T27/T19/T10 的官方备注回放 + canary | 突变 AUROC < 0.75 或恢复成功率 < 50% → 只保留 NRB |
| H3 | 共享技能槽比 32 个任务头/无路由在 held-out 任务上更好 | leave-8-task-out 离线 + canary | held-out 动作误差不降 → 关 SSR |
| H4 | A2A role token 在双手任务上有增益 | T18/T23/T31 配对 A/B | 双手任务 < +3pp → 关 A2A |
| H5 | 整体在 320 次评测上可感知 | 配对 canary + 正式跑 | 总成功率 < +2pp 或延迟 p99 > 150ms → 回退到 SAVE-lite |

**现实预期**：不是 +20pp，而是 **+3–6pp 总成功率**，其中位置/背景/未见物品是主贡献，ELM 只在人为干扰轴（20% 权重）上贡献 +1–2pp 总量。这个量级已经需要配对设计才能测出来：320 次、p≈0.30 时 SE≈2.6pp，单次官方跑的 95% CI 约 ±5pp；必须用 canary 配对 + 离线 held-out，不能拿一次总分波动当结论。

## 7. 风险与合规（先立后破）

- **双目不一定可用**：`rectified=true` 但左右 `cx` 差 18px；评测相机是否同一对、是否同步、`image_resize` 后标定是否还成立，全部未确认。先做极线误差/桌面平面/EE 投影三重自检；失败就退到单目 DA3 + 运动学尺度，不把主路径押在未验证的深度上。
- **相机到基座外参未知**：API 不给外参；用桌面平面 + 双 EE 位置估 TAF，离线用官方数据标定，线上用平面残差和 EE 投影误差监控。
- **物体槽的域差**：SAM2/跟踪模型在透明/布料/小件上会错；线上不跑大模型，蒸馏成轻量 slot head；透明/布料任务回退到 2.5D 关系 + 抓取先验。
- **ELM 误报**：把正常遮挡当“被移动”会触发多余回退；用 precision-first 阈值 + 双证据（槽位移 + 关系变化），不确定时只重定位不重抓。
- **SSR 路由塌缩**：所有任务都选同一个技能槽；用熵/负载均衡 + 步骤标签辅助，离线检查路由分布。
- **A2A 过拟合**：只在双手任务上有增益；单臂任务保持 gate=0，避免拖累。
- **外部预训练权重/数据**：默认只用官方 33k；DINOv3/SAM2/DA3 只作为初始化/离线教师，模型卡披露；外部机器人数据默认 OFF，邮件确认后再议。
- **单模型边界**：SAVE 渲染器、ELM、SSR、A2A 全部在同一个 checkpoint 内；确定性预处理写进模型卡，不引入第二个策略。
- **延迟**：双目匹配 + DINOv3 + 工作区渲染可能超预算；目标是 p99 <100ms（至少 <150ms），用低分辨率几何分支、缓存、TensorRT/ONNX；超了就降频（工作区 10–15Hz，动作 30Hz）。
- **统计噪声**：320 次不够检测 3pp；用配对 canary、bootstrap、任务级分层，不拿占位榜调参。

## 8. 一句话押注

**在 UniBot 里，最值得押注的不是更大的 VLA，也不是字面意义的多机器人，而是把四路 RGB + 本体感知压成机器人基座系里一块持续更新的米制物体工作区（SAVE），用它同时做跨任务技能路由、短时干扰记忆和双臂/多视角共识——这是一次性打位置、干扰物、背景、未见物品四个轴、成本却只落在编码器和数据管线上的杠杆。**

## 1. 事实核对与校正

### 1.1 排名规则：成功率优先，步骤分只是 tie-break

官方参赛手册（中/英）[S1][S2]：

- 32 个任务，每任务 **10 次**独立运行；5 类泛化（位置/干扰物/背景/未见物品/人为干扰）**各 2 次**；共 **320 次计分运行**；
- 单次真机执行 **最多 180 秒**，超时记失败；
- **实时榜按 32 任务总平均成功率排序；成功率相同按总平均步骤分；仍相同按提交日期早的靠前**；
- 仅设通才模型赛道，**所有任务必须用同一个模型完成，不得混合多个模型**；模型类型不限；
- 选手自行部署，官方只做远程 API 调用；推理延迟与动作内容会被记录；
- 另有**不计分单任务调试通道**（1 个任务、不计分）[S24]。

**修正第 7 轮**：第 7 轮把“成功率与步骤分综合排序”当目标函数，并据此计算“终局放置 60% 步骤分”的排名增益。实际步骤分只在成功率完全相同时才起作用。终局放置仍是成功闸门（成功=所有步骤完成），但“部分分”不能直接换排名；**本轮以整条任务成功率为唯一主目标，步骤分只作诊断和 tie-break。**

### 1.2 公开榜单：8 条记录，但仍是占位

所以：**29.7% 只能当弱先验；不能推断真实头部方案、轴级瓶颈或“30% 天花板”。** 本报告所有“预览榜”数字都标“弱先验”，不参与调参。

### 1.4 任务结构：32 任务 / 94 步 / 3200 分，技能高度复用

32 个任务的 `score_steps` 合计 **94 个评分步骤、3200 分**；难度 12 Easy / 12 Medium / 8 Hard[S9]。对步骤文本做粗略关键词统计：

```text
Grab  19
Place 15
Put   10
Pick   6
----------------
合计  50 / 94 ≈ 53%
```

其余是 Open/Close/Zip/Fold/Pour/Plug/Stack 等。结论：

- 32 个任务不是 32 个互不相干的技能，而是“抓—运—放/插/合/倒”这组共享技能 + 不同物体/容器/关系；
- 跨任务泛化最合理的归纳偏置是 **共享物体关系槽 + 共享技能槽**，不是 32 个任务头；
- 32 个任务共享一个策略时，任务干扰是真实风险；共享槽 + 轻路由是解药。

### 1.5 API：四路 RGB + 本体，无 depth/外参/触觉

提交模板 README（v2）[S5]：

- 观测：4×RGB 480×640（左右高位 + 左右腕部）、双臂 7+7 关节、EE 位姿 6+6（base 系）、夹爪、下半身 15、`observation.language` 单字符串；
- 自由度：`obs_delta_indices` 选键 + 每键堆叠帧；`image_resize` 自定；`action_chunk_size` 自定；动作空间 joint 或 ee 互斥；
- **没有 depth、没有相机外参、没有触觉/六维力/电机电流**；
- `reset()` 每 episode 一次；token 双处校验；
- 多端口示例 N=3（8765–8767），要求并发安全、状态隔离；
- 每步推理延迟与动作内容会被记录。

这给出一个清晰的机会：**观测里没有 depth，但数据里有无标定双目；如果评测相机就是同一对，深度是可以从 RGB 自己算的。** 这比等官方给 depth 更现实。

### 1.6 “多机器人协作”在正赛里没有对应任务

官方 32 个任务都是单台 G1 的桌面操作；评测用多台机器人是并行载体，不是协作任务；API 没有机器人间通信、队友观测、共享动作字段[S1][S5][S6]。字面做 multi-robot：

- 没有评测信号，无法进入 320 次计分；
- 与“单模型 + 单机任务”的形态不符；
- 会把预算从真正能加分的感知/操作上挪走。

所以本轮把它翻译成：

1. **多视角团队**：head stereo + wrist ×2 是四个视角代理，对同一个物体槽投票；分歧=遮挡/反光/被移动。
2. **双臂团队**：左右臂是两个执行代理，用 role token 协调；对应 PackBag/OrganizePencilCase 等双手任务。
3. **跨具身团队（可选，默认关闭）**：CHORUS 证明一个共享 VLA backbone 可以控制不同机器人团队，但 UniBot 没有机器人间协作；只借“共享策略、局部观测”的原则，不引入机器人间通信，也不把外部机器人数据当主粮[S16]。

### 1.7 基座：WLA-1.0-Base 已开源，SAVE 可以直接挂

`UnifoLM-WLA-1.0-Base`：6B，约 2,500 小时真机数据、64 个任务，Apache-2.0；官方微调默认冻 VLM、训 action expert（DiT），单卡 24GB 可跑，支持 LoRA（默认 r=16，可调）[S19]。这决定了 SAVE 的落地方式：

- 不换基座、不从零预训练；
- 先冻 VLM，只训 SAVE projector + action expert LoRA；
- 如果 OOD 不升，再考虑解冻视觉塔的高秩 LoRA，而不是全量重训。

### 1.8 研究证据：视觉编码器/双目/跨任务/记忆

| 方向 | 证据 | 对本轮的含义 |
|---|---|---|
| 物体中心 | SlotVLA 用 slot-attention 建模物体与关系，显著减少视觉 token，保持竞争性泛化[S10] | 槽是跨任务共享接口 |

## 2. 定量分析：为什么是“工作区”，不是“更大的 VLA”

### 2.1 五轴预算：四轴是视觉，一轴是状态突变

五类泛化各 2/10 次，即各占 20%：

| 轴 | 占比 | 失败机制 | SAVE/ELM 对策 | 现实增益假设 |
|---|---:|---|---|---:|
| 位置 | 20% | 单目尺度/相机坐标 | 双目 + TAF + 基座系 | +5–8pp |
| 干扰物 | 20% | 物体/背景纠缠 | 物体槽 + 关系 | +4–6pp |
| 背景 | 20% | 纹理 shortcut | WSI 俯视图 | +5–8pp |
| 未见物品 | 20% | 语义/形状 OOD | DINOv3 dense + 槽几何 | +4–7pp |
| 人为干扰 | 20% | 状态突变/无记忆 | ELM + NRB | 该轴 +5–10pp |

如果前四轴各 +4–6pp、第五轴 +5–10pp，总成功率约 **+3.6–5.8pp**。这不是“翻倍”，但在 320 次评测上是可感知的；而且它不依赖某个任务的 special case。

### 2.2 双目深度精度：桌面距离够用，远处不够

用 `f≈282.4 px`、`B≈0.05825 m`，`fB≈16.45 px·m`：

```text
Z = 0.4 m  -> disparity ≈ 41.1 px; 0.5 px 误差 -> δZ ≈ 4.9 mm
Z = 0.6 m  -> disparity ≈ 27.4 px; 0.5 px 误差 -> δZ ≈ 10.9 mm
Z = 0.8 m  -> disparity ≈ 20.6 px; 0.5 px 误差 -> δZ ≈ 19.5 mm
```

所以：

- 桌面 0.3–0.6m 范围，双目深度足够支撑“抓取/放置/插入”的厘米级需求；
- 0.8m 以外误差接近 2cm，不适合精细插入；
- 腕部相机不参与全局深度，只做局部抓取/接触；全局工作区以 head stereo 为主。

这是 SAVE 只把双目用于“桌面工作区”的原因：**不追求全场景深度，只追求操作台那块 0.3–0.6m 的米制精度。**

### 2.3 320 次评测的功效：不要拿一次总分证明 3pp

p≈0.30、n=320：

```text
SE = sqrt(0.30 × 0.70 / 320) ≈ 2.56pp
95% CI ≈ ±5.0pp
```

也就是说，**单次官方跑对 +3pp 的真实改进几乎没有分辨力**。必须：

- 用配对 canary（同一任务、同一场景，A/B 交替）降低方差；
- 用离线 held-out（object/background/position）做机制验证；
- 用任务级分层/bootstrap，而不是只看总分；
- 不拿占位榜调参。

### 2.4 为什么是“工作区”，不是“更多 token”

VLA 的视觉塔输出 2D patch tokens，语义强、尺度弱、背景纠缠。UniBot 需要的是：

```text
“碗在盘子左边 12cm、杯把朝右、插座在桌子后沿、左手当前在 (x,y,z)”
```

而不是：

```text
“这是一张有碗、盘子、插座的桌面图”
```

工作区表示把“在哪里/是什么关系/是否被移动”显式化，动作专家不需要从纹理里反推几何。它也天然跨任务：抓取、放置、插入、闭合都读同一块工作区。

### 2.5 为什么是“共享槽”，不是“32 个任务头”

50/94 步是 Grab/Place/Put/Pick；32 个任务共享技能词汇。如果每个任务一个头：

- 数据少的任务过拟合；
- 任务间不能迁移；
- 不符合“通才单模型”的精神；
- 32 个头的审计/部署复杂。

共享槽 + SSR 的参数量远小于 32 个头，且每个任务只改变“路由权重”，不改变“物体/技能词汇”。这是 cross-task 的正确归纳偏置。

### 3.2 SAVE：双目锚定的视觉环境

**输入**：head stereo `I_L, I_R`（480×640）、wrist `I_WL, I_WR`、本体状态 `q`、语言 `l`。

**步骤**：

1. **立体匹配**：用轻量 stereo matcher（FoundationStereo/ExStereo 类）在 480×640 上算视差；输出深度 `Z` 和 valid mask。若评测分辨率被 `image_resize` 改过，按比例缩放 `K`；若标定不可用，先做极线自检，失败则回退单目。
2. **反投影**：`P_C = K^{-1} [u,v,1]^T Z`，得到头系点云。
3. **桌面平面**：RANSAC 拟合桌面 `(n, h)`；用 waist/gravity 方向定符号；目标残差 <5mm。
4. **TAF**：用桌面法向、重力/腰方向、双 EE 位置解 `T_{B←C}`（§3.3）。
5. **基座系点云**：`P_B = T_{B←C} P_C`；只保留桌面以上 0–40cm 的操作带。
6. **物体槽**：class-agnostic slot head（K=16–32）从 DINOv3 dense features + 点云 + mask 得到；每个槽输出：
   - `μ ∈ R^3`（基座系质心）
   - `Σ ∈ R^{3×3}`（协方差/尺寸）
   - `R ∈ SO(3)`（主轴/朝向）
   - `v ∈ R^3`（速度）
   - `c ∈ R^d`（DINOv3 语义特征）
   - `vis ∈ [0,1]`（可见性）
   - 关系 `r_ij`：距离、上下、内外、接触、支撑。
7. **WSI**：把槽渲染成 256×256 俯视工作区图（§3.5）。

**关键设计**：SAVE 不替代 WLA 的语义塔；它是一条**并行的几何/物体通路**，输出 token 与 WSI，和 VLM token 在 action expert 里融合。这样既保留语言先验，又补上米制/关系。

### 3.3 TAF：没有外参，也能把点云放进基座系

评测 API 不给相机外参；但桌面场景给了三个锚：

1. **桌面平面**：头系点云里最大平面，法向 `n`、高度 `h`。
2. **重力/腰方向**：`state_torso`/`waist_state_joint` 给出机器人基座的姿态先验；桌面法向与基座 z 轴对齐（允许小倾角）。
3. **双 EE 位置**：`left/right_ee_pose_gripper_base` 是基座系；同一时刻的腕部相机/夹爪在头系点云里可见；用两个 EE 的基座坐标与头系坐标做 Procrustes/Umeyama，解平面内的旋转和平移。

```text
T_{B←C} = argmin_{R,t} Σ_{a∈{L,R}} || R p_C^a + t - p_B^a ||^2
s.t.      R n_C = z_B,  det(R)=1
```

尺度由双目米制给出；如果退化到单目，则用双 EE 距离定尺度。线上监控：

```text
epipolar_error < 1 px
table_plane_residual < 5 mm
EE_reprojection_error < 2 cm
depth_valid_ratio > 0.7
```

任一失败：降低 SAVE 置信度，回退到“单目 DA3 + 运动学尺度 + 2.5D 关系”，不直接关掉策略。

**为什么不做全局 SLAM/相机标定**：UniBot 是固定桌面、固定机器人基座、固定相机支架；不需要 SLAM。TAF 只解一个局部刚体变换，足够稳、足够便宜。

### 3.4 物体槽：跨任务共享的接口

**槽类型**（不依赖任务分类器）：

- `object`：被操作物（杯、碗、书、工具、电池、插头…）
- `container`：容器/支架/盒子/盘子/插座
- `tool`：工具/笔/注射器/夹爪可持物
- `target`：PGL 渲染的目标锚点/槽位
- `robot`：双 EE/夹爪/手臂（用于关系）

**槽特征**：

```text
slot = [μ, Σ, R, v, c, vis, type, relations]
relation_ij = [Δp, distance, above/below, inside/outside, contact, support]
```

**训练标签**：SAM2/跟踪模型离线产出 mask/ID；蒸馏到轻量 slot head。线上不跑 SAM2；只跑 <20M 的 slot head。透明/布料/小件用 2.5D 关系 + 抓取先验兜底。

**关系谓词**（直接服务 SSG/SVL）：

```text
on(bowl2, bowl1)
in(plug, strip)
closed(zipper)
inside(cup, rack)
held(cup, right_gripper)
```

这些谓词是确定性的几何/学习混合，不依赖任务特定头。

### 3.5 WSI：把工作区渲染成一张图

**规格**：

```text
256×256 top-down, 1 cm/pixel, 覆盖桌面 2.56m × 2.56m（可按任务裁剪）
channels:
  0 height above table (normalized)
  1 object instance ID / embedding
  2 semantic color (optional)
  3 memory delta (where object was 1–3s ago)
  4 left EE / gripper
  5 right EE / gripper
  6 target anchor / PGL slot
  7 confidence (depth valid, slot vis)
```

**编码**：ResNet-18 或 ViT-S，输出 256 tokens；projector 到 action expert 维度。渲染 10–15Hz，动作 30Hz；缓存最近一帧。

**为什么有效**：

- 俯视图与相机视角/背景纹理解耦 → 背景轴；
- 物体位置/关系显式 → 位置轴、干扰物轴；
- 目标锚点/EE 同图 → 跨任务共享；
- 记忆残影 → 人为干扰轴（看到“原来在哪、现在在哪”）。

**合规**：WSI 是确定性预处理，不是第二个策略；写进模型卡。

### 3.6 ELM：1–3 秒的物体记忆，不是长视频库

**状态**：每个槽最近 `T=1.5s`（45 帧）的 `μ, v, vis, relations`。

**预测**：

```text
μ̂_t = μ_{t-1} + v_{t-1} Δt
a_t = sqrt((μ_t - μ̂_t)^T Σ^{-1} (μ_t - μ̂_t))   # Mahalanobis
```

**突变判定**：

```text
moved(s)    = a_t > τ_move(s) and vis_t > 0.5
removed(s)  = vis_t < 0.2 for > 0.3s and was visible
appeared(s) = new slot with stable mask for > 0.3s
relation_changed(i,j) = predicate_ij(t) != predicate_ij(t-1)
```

阈值 `τ_move(s)` 按槽尺寸/深度方差校准；precision-first：不确定时只重定位，不重抓。

**触发动作**：

- `moved/removed`：更新目标/容器位姿，SSG 回退到当前步，PGL/OPT 重算锚点；
- `relation_changed`：若当前步骤谓词从 1→0（如拉链被拉开、插头被拔起），触发 NRB 恢复；
- `appeared`：若是任务目标（人把物体放回），重新纳入槽，不重启 episode。

**训练**：官方数据正常轨迹 + 备注回放的“移动/移除/撤销”状态序列；BCE + 对比学习；不训练长视频记忆。

**与 MemoryVLA/Chameleon 的区别**：它们是长程/情景记忆，存低层细节与语义；ELM 只存物体槽的短时状态，参数 <5M，目标是“发现状态变了”，不是“回忆十分钟前”。

### 3.7 SSR：共享技能槽路由

**技能词汇**（12 个）：

```text
reach, grasp, lift, transport, place, insert,
press, close, open, pour, fold, zip/handover
```

**路由器**：

```text
h = [lang_emb(l), step_emb(s), slot_summary]
π = softmax(W h)                  # K=12
z_skill = Σ_k π_k e_k
```

`z_skill` 作为 action expert 的 condition token；top-2 也可，但保留 soft mixture。

**训练信号**：`score_steps` 的动词（Grab/Place/Put/Pick/Open/Close/Zip/Fold/Pour/Plug/Stack）自动给标签；无需额外标注。

**防塌缩**：熵正则 + 负载均衡 + 步骤标签辅助；离线检查每个任务的 π 分布，若 80% 任务都选同一个技能槽，判失败。

**合规**：SSR 是单一 checkpoint 内的 token 路由，不是 32 个模型/头；参数量 <1M。

### 3.8 A2A：双臂角色注意力（可选）

**角色**（从演示自动挖）：

```text
hold        一手闭合保持，另一手操作
manipulate  一手闭合且移动
handover    两手都闭合后一手松开
bimanual    两手一起抬/一起推
single      单臂任务
```

**结构**：

- 左右臂 token 序列 + role embedding；
- cross-attention：左→右、右→左；
- gate：语言/步骤预测是否需要双臂；单臂任务 gate=0。

**证据**：ACG-Bench/AE-VLA 的 arm-wise attention + SkillLoRA 在未见双臂组合上 21.53% vs 单 π0.5 2.94%；真机 39.00% vs 10.00%[S25]。UniBot 的 PackBag 等任务双手参与度高，A2A 值得做；但它只影响双手子集，所以标“可选”，不作主押注。

### 3.9 与 WLA 的接口

**输入 token 序列**：

```text
[VLM semantic tokens] + [SAVE object tokens] + [WSI tokens] + [proprio tokens] + [skill token] + [role tokens]
```

**训练**：

- 冻结 VLM（官方默认）；训练 SAVE projector、slot head、ELM、SSR、A2A、action expert LoRA；
- 若显存允许，解冻视觉塔最后 2–4 层做高秩 LoRA（r=64–128），但先做消融；
- 动作头沿用 WLA 的 flow matching / DiT；chunk 16–32，horizon 1–2s。

**推理**：

```python
obs = receive()
slots, wsi, conf = save.encode(obs)
s = ssg.step(obs.language, slots)
mem = elm.update(slots)
skill = ssr.route(obs.language, s, slots)
roles = a2a.roles(obs.language, s, slots)
action = policy.act(obs, slots, wsi, mem, skill, roles, s)
send(action)
```

**单模型边界**：SAVE/ELM/SSR/A2A 全部在 policy checkpoint 内；stereo matcher/WSI renderer 是确定性预处理；slot head 是同一 checkpoint 的子模块。模型卡逐项披露。

### 3.10 最小可运行版（MVP）

如果时间/算力只够做一件事：

1. **不重训 WLA**：用 SAVE 生成 WSI + 槽 overlay，作为额外观测；冻 WLA，只训一个小 projector + action expert LoRA。
2. **先验证模型会不会用工作区**：在 T27（叠碗）和 T10（插排）的调试槽，比较“原始四路 RGB” vs “原始 + WSI overlay”。
3. **如果 overlay 被忽略**：不是工作区没用，而是注入方式不对；改用 cross-attention token 注入（SAVE token + WSI token），进入全量训练。
4. **ELM/SSR/A2A 后置**：先证明 SAVE 的几何/工作区有效，再加记忆/路由/双臂，避免一次改太多无法归因。

- 四路 RGB、stereo 标定、双臂/EE/夹爪/腰、5 条复述、`score_steps`[S5][S7][S8][S9]；

- 外部预训练权重（DINOv3/SAM2/DA3）只作初始化/离线教师，模型卡披露；外部机器人数据默认 OFF。

### 4.2 处理流水线

```text
episode
  ├─ 读四路视频 + 状态 + 语言
  ├─ head stereo 立体匹配 → 深度/点云（每 2–3 帧，不必每帧）
  ├─ 桌面平面 RANSAC → TAF → 基座系点云
  ├─ SAM2/跟踪离线 mask → 槽 ID/轨迹
  ├─ DINOv3 dense feature → 槽语义
  ├─ 关系图（距离/上下/内外/接触）
  ├─ score_steps → 步骤相位/动词标签
  └─ 写 shard：slots.npz + wsi.png + meta.json
```

### 4.3 标签

| 标签 | 来源 | 用途 |
|---|---|---|
| 深度/点云 | 立体匹配（自监督） | SAVE 几何 |
| 物体 mask/ID | SAM2 + 跟踪离线 | slot 蒸馏 |
| 槽质心/协方差/朝向 | 点云 + mask | 工作区/关系 |
| 关系 | 几何规则 | SSG 谓词/SVL |
| 步骤/动词 | `score_steps` + 语言 | SSR/SSG |
| 夹爪闭合/角色 | 夹爪 state + EE 运动 | A2A |
| 干扰事件 | 官方备注 + 状态回放 | ELM |
| 放置位姿 | EE base 位姿 + 容器槽 | OPT/PGL |

### 4.4 数据划分

- **ID**：官方同分布 held-out episode；
- **object-held-out**：23 个有 `unseen_object_3` 备注的任务，按对象变体留出；
- **background-held-out**：背景替换/重渲染；
- **position-shift**：目标/容器平移；
- **human-replay**：T27/T19/T10 等备注的状态级回放；
- **leave-8-task-out**：跨任务泛化离线代理（不是官方评测）。

注意：官方评测的 5 轴是隐藏的；这些划分只用于机制验证，不能当官方分数。

### 4.5 增广（克制）

- **视角增广**：在点云/WSI 里轻微扰动相机位姿，训练 TAF/槽的视角鲁棒；
- **背景增广**：替换桌面纹理/颜色，训练 WSI 的尺度/颜色不变；
- **位置增广**：平移物体槽/目标锚点，训练关系/放置；
- **对象替换**：只在 2.5D 槽级做，默认不生成照片级假数据；若用 3D 资产，逐个核许可；
- **干扰回放**：状态级（移动/移除/撤销），不追求照片级真实，ELM 只学状态序列。

### 4.6 QA

```text
depth_valid_ratio > 0.7
epipolar_error < 1 px
table_plane_residual < 5 mm
EE_reprojection_error < 2 cm
slot_track_consistency > 90%
mask_area_sanity (0.5×–2× 中位数)
language/step alignment (verb match)
```

任一批次拒绝率 >20% 停采/停训，先修标定/跟踪。

### 4.7 合规

- 只用官方数据训练；预训练权重披露；
- 不引入外部机器人数据/外部评测数据；
- 不把官方 human 备注当“已知评测剧本”写死，只做训练增广；
- 单模型：所有学习组件在同一 checkpoint；确定性预处理器写进模型卡；
- 若规则禁止额外预训练权重，回退到 WLA 自带视觉塔 + 官方数据蒸馏。

| 项 | 含义 | 起始权重 |

| L_skill | 动词/步骤分类 | 0.1 |

### 5.2 课程

| 阶段 | 数据 | 目标 | 退出条件 |
|---|---|---|---|
| 0 | 官方 100% | 复现 WLA 基线 | 真实 held-out 不降 |

| 3 | + ELM | 突变检测/回退 | AUROC >0.80 |
| 4 | + SSR | 技能路由不塌缩 | 路由熵/任务覆盖达标 |

| 6 | 全量 + 量化/蒸馏 | 延迟达标 | p99 <150ms |

### 6.2 Canary（不计分单任务调试槽）

### 6.3 正式跑

- 320 次计分；成功率主指标，步骤分诊断；

### 6.4 统计

```text
Wilson CI for success rate
paired bootstrap for A/B
task-level stratified analysis
no peeking on placeholder leaderboard
```

单次 320 次只能分辨 ~5pp；+3pp 需要配对/重复。报告里明确“未显著”而不是“有效”。

## 8. 创新点清单（动机/差异/可行性/资源/步骤/风险/状态）

> 状态：押注=本轮主线；支撑=有用但非主押；可选=视结果；升级=旧点改造；砍=不做。

### I1 SAVE 双目物体工作区（新增，押注）
- 动机：五轴里四轴是视觉分布偏移；API 无 depth，但官方数据有 stereo 标定。
- 差异：不是再加一个语义塔，而是输出基座系米制物体槽 + 工作区图；现有 StereoVLA/ExStereo 有双目但没有持久物体工作区/跨任务槽。
- 可行性：官方数据有 stereo 标定；WLA 可挂 projector；单卡可训。
- 资源：立体匹配 + 槽标注 4–6 天；训练 2–3 周。
- 步骤：标定自检→深度→TAF→槽→WSI→注入 WLA。
- 风险：评测相机不是同一对/标定失效→回退单目/WSI-lite。
- 状态：押注。

### I2 TAF 桌面锚定（新增，支撑）
- 动机：API 无外参；没有基座系，工作区无法跨视角/跨任务共享。
- 差异：不跑 SLAM，只用桌面平面 + 重力/腰 + 双 EE 解局部刚体变换。
- 可行性：桌面平面稳定，双 EE 已知；残差可监控。
- 资源：CPU，<5ms。
- 步骤：平面→方向→Procrustes→残差门控。
- 风险：桌面被遮挡/倾斜→置信度下降，回退。
- 状态：支撑。

### I3 WSI 俯视工作区图（新增，支撑）
- 动机：背景/视角/纹理是 OOD 主因；需要一块规范化的“地图”。
- 差异：把物体槽/EE/目标/记忆渲染成 2.5D 图，而不是让 VLA 从原图反推。
- 可行性：确定性渲染；256×256 便宜；可直接可视化调试。
- 资源：<5ms/帧；10–15Hz。
- 步骤：槽→栅格化→通道→CNN/ViT→token。
- 风险：渲染域差→训练/推理同管线；颜色通道可关。
- 状态：支撑（也是 MVP 首选）。

### I4 ELM 短时物体记忆/突变检测（新增，押注）
- 动机：官方 human 备注是“移动/撤销”，需要 1–3 秒内发现状态变了。
- 差异：不是长视频记忆库，只存物体槽轨迹 + 恒速预测 + 突变分数；<5M。
- 可行性：槽轨迹可从官方数据自动生成；备注可状态级回放。
- 资源：1 人周 + 少量训练。
- 步骤：槽轨迹→预测→阈值→触发 SSG/NRB。
- 风险：遮挡误报→precision-first + 双证据。
- 状态：押注。

### I5 SSR 共享技能槽路由（新增，支撑）
- 动机：50/94 步共享 Grab/Place/Put/Pick；32 个任务头会过拟合/干扰。
- 差异：K=12 技能 token，单 checkpoint 内 soft 路由；不是 32 个 LoRA/专家。
- 可行性：score_steps 直接给动词标签；<1M。
- 资源：几天。
- 步骤：动词标签→router→熵/负载均衡→消融。
- 风险：路由塌缩→熵正则/步骤辅助。
- 状态：支撑。

### I6 A2A 双臂角色注意力（新增，可选）
- 动机：PackBag 等任务双手参与；ACG-Bench 证明 arm-wise 结构关键。
- 差异：role token + 左右臂 cross-attention，单 checkpoint，单臂 gate=0。
- 可行性：夹爪/EE 时间线自动挖角色。
- 资源：<5M；几天。
- 步骤：角色标签→cross-attention→双手 canary。
- 风险：只影响双手子集→不主押。
- 状态：可选。

### I7 SSG v2（升级，保留）
- 动机：官方步骤图仍是成功闸门；谓词改为物体关系后更稳。
- 差异：从图像分类谓词→槽关系谓词（on/in/closed/held）。
- 可行性：SAVE 槽直接给关系。
- 风险：关系噪声→几何规则 + 学习头双保险。
- 状态：保留/升级。

### I8 PGL/OPT/SVL v2（升级，保留）
- 动机：放置/插入仍是终局闸门；槽位姿比 2D 检测稳。
- 差异：容器 6D 槽→锚点→EE 位姿；SVL 用槽位移判稳定。
- 可行性：官方 EE 位姿 + 槽几何。
- 风险：透明/布料→分桶回退。
- 状态：保留/升级。

### I9 ICR/NRB v2（升级，保留）
- 动机：检索/恢复仍有用，但 key 要从外观改成关系/运动。
- 差异：ICR key=物体关系+运动；NRB 用 ELM 检测撤销后触发。
- 可行性：官方数据可建库；备注可回放。
- 风险：检索延迟→缓存/降 K。
- 状态：保留/升级。

### I10 DebugLoop/CanarySuite（保留，流程）
- 动机：SAVE 的收益必须真机验证；单次 320 次功效不够。
- 差异：固定 T01/T10/T19/T27/T18 五个 canary + 配对 A/B + 杀停线。
- 可行性：官方单任务调试槽已存在。
- 风险：槽位稀缺→每版本最多 1–2 次。
- 状态：保留。

### 已砍/降级
- 字面多机器人协作、机器人间通信；
- 32 个任务头/每任务 LoRA；
- 全 32 任务高保真孪生、自由仿真数据、运行时 MPC/仿真 RL；
- 把步骤分当第二目标；
- 基于占位榜的头部方案推断；
- 无脑叠 SigLIP/CLIP/额外视觉塔（R2-WAM 警告不总是可加[S17]）；
- 长视频记忆库（UniBot episode 太短）；
- 外部机器人数据（默认 OFF）。

## 12. 开放问题

1. 评测的 `cam_left_high/right_high` 是否就是训练数据里的 head stereo 同一对？是否同步？`image_resize` 后标定是否还成立？
2. 官方数据是否提供相机到机器人基座的外参？若没有，TAF 的双 EE 估计在真实评测场景是否稳定（桌面被遮挡/反光/倾斜）？
3. `rectified=true` 但左右 `cx` 差 18px：是原始标定还是已校正？需要怎样的自检/重标定？
4. 外部预训练权重（DINOv3/SAM2/DA3）是否允许？官方数据派生的深度/槽标签是否允许？
5. 评测是否允许模型侧增加派生观测（WSI/槽图）？还是只能喂四路 RGB？若只能 RGB，是否允许把 WSI 编码进额外通道/模型内部？
6. 单模型边界：确定性 stereo/TAF/WSI renderer 是否算“第二个模型”？模型卡如何披露？
7. 不计分单任务调试槽的可用次数/成本/是否可固定场景做配对 A/B？
8. 官方 human 备注的编号含义（轴/试次）是否就是评测剧本？ELM 的训练回放是否需要覆盖通用扰动？
9. 真实榜单何时发布？真实轴级瓶颈是否与占位榜一致？
10. 双目 matcher 在透明/反光/细线（网线、拉链、试管）上的失败率；是否需要学习式 stereo 或置信度门控？
11. 32 个任务中双手任务的真实比例；A2A 的收益是否值得其复杂度？
12. WSI 的 1cm/pixel 是否足够精细（小件电池/药片/针头）？是否需要 0.5cm 局部放大图？
