# 第 5 轮（灵感循环第 5 轮；本轮灵感：「角色一致性」×「UniBot世界挑战赛」）

> **基线**：第 4 轮 InstructGauge-WR（IP-328–333；定义 448–467；引理 59–62；实验 E457–E472）。第 3 轮 InstructGauge 的五不变式、CVC 闭环与严格退化链继续继承不变。
> 本轮纪律：**角色是过滤器，不是生成器**。角色一致性只允许收缩可采纳动作集、缩短块长、拒绝越权交接；任何角色模块失效都必须能逐级退回 WR v4 → InstructGauge v3 → ToolGauge。

## 0. 直觉与动机

**灵感 1（角色一致性 → 不是「人设不崩」，而是「权限—义务—指代在时间上不漂移」）**
直觉：在 UniBot 这类「单模型、多任务、真机泛化」的挑战里，同一个策略要在抓取、放置、双手协调、失败恢复之间切换。人类看一个操作员是否可靠，不只看他某一步做得好不好，而看他「是否始终清楚自己现在是谁、能做什么、该对什么负责」：抓取角色不能偷偷做放置的释放动作，双手任务里左右臂的主从角色不能在未交接时互换，语言指令指代的对象不能在一个动作块内悄悄换掉。因此「角色」不是提示词里的人设，而是一份**带权限、义务、终止条件与预算的执行契约**；「角色一致性」是一条**可检查的轨迹性质**，而不是一句主观评价。
更关键的是，角色一致性有两种失败：一种是**角色漂移**（越权、静默换角、指代漂移），另一种更危险——**角色选错但全程一致**。后者会产出「证书齐全、动作流畅、任务稳定失败」的系统。所以本轮必须把「一致性」与「正确性」分开：一致性负责可审计与可退化，正确性仍由任务证据与隐藏分布评测负责。

**灵感 2（UniBot 世界挑战赛 → 把角色一致性从哲学问题变成隐藏分布下的统计问题）**
直觉：UniBot-V1 公开赛制给出的不是一个干净实验室，而是一个**单模型多任务的真机泛化考场**：32 项桌面任务、32000 条演示、169 小时数据，按平均成功率与步骤分排序，评测跨多台机器人、随机化对象与场景，策略接口是带时间轴的动作块（`action_chunk_size`），观测里同时有左右高视角、左右腕部相机、双臂关节/末端位姿、夹爪状态与自然语言指令。这个设置恰好把第 3/4 轮的「指令—分块—腕部证据」串起来，但也暴露了一个新缺口：**公开任务覆盖的是角色词表，隐藏任务考验的是角色组合**。抓取→放置、双手交接→单臂回退、失败恢复后再抓取，这些角色 bigram / trigram 在公开集里可能稀疏；一旦隐藏任务落在未覆盖的组合上，系统不会「不知道」，而会**用一个错误的角色非常一致地执行下去**。
因此挑战赛不是背景板，而是本轮的**可证伪评测协议**：角色一致性必须同时报告公开任务上的成功率/步骤分，和隐藏对象/背景/扰动下的角色组合覆盖率与角色归因失败率。

**灵感 3（两者耦合 → 一致性 vs 适应性，必须用「交集语义 + 交接证书 + 覆盖账本」压成可退化）**
直觉：挑战赛奖励「一个模型多任务」，这天然要求角色可切换；但安全审计又要求角色稳定。最危险的耦合是：**一句模糊指令 + 一个长动作块 + 一个未预注册的角色组合**。此时若系统为了「保持一致」而强行选一个角色，就会把语义歧义沿时间轴放大成 K 步错误动作；若系统为了「适应」而自由换角，又会制造越权与不可审计的静默切换。
解法不是二选一，而是三根结构支柱：
1. **类型化角色契约**：角色只能从预注册技能/工具/夹爪语义/工作空间中做选择，语言不能造出新能力；
2. **证书化角色交接**：换角只能发生在声明的交接点，必须同时满足前角色后置条件、后角色前置条件、指代持续或重接地、证据新鲜、独立校验；不可逆动作强制角色冻结且 K=1；
3. **歧义交集语义 + 覆盖账本**：当语言/视觉给出多个候选角色时，只执行**所有候选角色可采纳集的交集**；交集为空则弃权/保持。再用角色分层覆盖账本与角色条件化共形校准，显式记录「哪些角色组合没被公开数据覆盖」，把隐藏组合风险从不可见变成可预算。
这三根支柱的共同点是：**只收缩、不扩张**。角色层永远不能比基座策略多做一个动作，只能少做、晚做、或拒绝交接。

## 1. 研究问题（本轮要回答什么）

- **Q1（可检查性）**：能否把「角色一致性」定义成一条只依赖可观测轨迹的判定性质，使得角色层可以被证明为基座策略的**过滤器**（`RC ⊆ WR`），而不是新的能力来源？
- **Q2（交接可靠性）**：抓取→放置、双手主从臂交换、恢复→再抓取这些角色交接，能否用证书化的前置/后置/指代/证据条件做到「无误接受、可拒绝、可回退」？不可逆动作如何强制冻结？
- **Q3（隐藏分布下的统计有效性）**：当 UniBot 隐藏任务改变对象、背景、扰动与角色组合时，按角色分层的共形校准能否恢复覆盖保证？覆盖债能否预测隐藏任务上的角色归因失败？
- **Q4（一致性的代价）**：角色一致性对官方成功率/步骤分的代价是多少？在覆盖债高、角色置信度低或指令歧义时，何时应退到交集语义、保守原语或基座策略？

## 2. 操作性定义（正式化见产物区定义 468–487）

**角色契约**：`ρ = (κ, α, Act_ρ, Pre_ρ, Post_ρ, Ev_ρ, Term_ρ, B_ρ)`。其中 `κ` 是技能族（抓取/放置/双手/恢复/扫描），`α` 是臂角色分配（单臂、左主右辅、右主左辅），`Act_ρ` 是动作谓词（控制空间、工作空间、夹爪语义、速度/力上界），`Pre/Post` 是前后置条件，`Ev_ρ` 是证据义务，`Term_ρ` 是终止谓词，`B_ρ` 是时间/步数预算。

**角色一致轨迹**：轨迹 `τ = (s_0, a_0, r_0, …, s_T)` 一致，当且仅当每一步恰好一个活动角色、`a_t ∈ Act_{r_t}`、换角处有有效交接证书、指代对象保持不变或被重新接地、屏障处 `K=1` 且独立校验签名存在。

**角色漂移**：分解为权限漂移（越权动作）、臂角色漂移（左右主从交换）、指代漂移（目标对象 track 改变）、时间漂移（角色超过终止条件仍继续）。四个分量任一为正即不一致；软版本用加权和作为 `D_role`。

## 3. 四条设计原则（雏形）

**P1 角色类型化（Role Typing / Capability Closure）**
语言与视觉只用于在预注册角色词表中选择、绑定指代与排序，不能命名新技能、不能越过夹爪/工作空间/控制空间的类型边界。角色编译器的输出是候选角色集合，不是自由动作。

**P2 证书化角色承诺与交接（Certified Role Commitment & Handoff）**
角色在一个承诺窗口内保持稳定；换角只发生在声明的交接端口。交接证书同时检查：前角色后置条件、后角色前置条件、指代持续或重接地、证据新鲜、校验者独立。抓取闭合、释放、双手交接等不可逆/高风险动作进入屏障：角色冻结，`K=1`，先验证再继续。

**P3 歧义交集语义（Ambiguity Intersection Semantics）**
当指令/视觉给出多个候选角色时，不猜一个，而是执行 `∩_{ρ∈R_amb} Act_ρ`；交集为空则保持/弃权。这样无论真实角色是哪一个，执行的动作都不会越过任何一个候选角色的权限。代价是保守，收益是「歧义不放大成越权」。

**P4 角色分层覆盖与校准（Role-Stratified Coverage & Conformal）**
维护角色、角色 bigram、角色×对象类/场景层的覆盖账本；覆盖债高的层进入保守模式。共形校准按角色分层，冷启动或样本不足时逐级回退到父层/全局阈值，并显式标记「覆盖未认证」，而不是假装覆盖成立。

## 4. 与基线的接口（如何退化）

- 角色编译器不可用 / 指令不可接地 ⇒ 不产生角色约束，直接使用 WR v4 基座策略；
- 角色交接证书无效 ⇒ 保持当前角色或回到上一个已认证前缀，必要时 `K=1`；
- 角色分层样本不足 ⇒ 回退父层/全局共形阈值，并标记低置信；
- 覆盖债超过预算 / 候选角色交集为空 ⇒ 进入保守原语或弃权，不自由换角；
- 角色监控本身失效 ⇒ 退回 WR v4 的 CVC + SpatialCert 路径；
- WR v4 失效 ⇒ InstructGauge v3；InstructGauge 失效 ⇒ ToolGauge；ToolGauge 失效 ⇒ LeanGauge 纯数值路径。

## 5. 预期贡献

1. 一个「角色 = 类型化执行契约」的口径，把角色一致性从主观人设变成可检查的轨迹性质，并证明角色层只是基座策略的过滤器；
2. 一个带**交接证书 + 不可逆屏障**的角色状态机，覆盖抓取→放置、双手主从交换、恢复→再抓取等 UniBot 典型角色切换；
3. 一个**歧义交集语义**，让模糊指令下不靠猜测也能保持权限安全，并量化其保守代价；
4. 一个**角色分层覆盖账本 + 角色条件化共形校准**，把隐藏任务上的「角色组合未覆盖」风险显式化、可预算、可退化；
5. 一条完整可证伪路径：E473–E488 覆盖权限泄漏、交接可靠性、漂移检测、歧义交集、分层覆盖、隐藏组合泛化、跨机器人一致性与官方成功率/步骤分。

## 6. 本轮最大风险

**一句话**：角色一致性最大的风险不是「角色漂移」，而是「角色选错却全程一致」——在 UniBot 的隐藏任务分布下，越强的角色闭包越可能把一个未预注册的正确角色组合拒之门外，最终得到「证书齐全、动作流畅、稳定失败」的系统；因此一致性的收益必须用隐藏组合覆盖率与任务成功率同时证伪，而不能只看审计指标。

## 2. 形式化定义（要点）

**定义 468（角色契约）**
```
ρ = (κ, α, Act_ρ, Pre_ρ, Post_ρ, Ev_ρ, Term_ρ, B_ρ)
```
其中 `κ ∈ K = {grasp, place, bimanual, recover, scan}`；`α ∈ {single, L-main/R-support, R-main/L-support}`；`Act_ρ ⊆ A × S` 是可判定动作谓词，至少约束：控制空间（joint/ee）、臂角色、工作空间、夹爪开合语义、速度/力上界；`Pre_ρ, Post_ρ: S → {0,1}`；`Ev_ρ = (freshness, modality, cert)`；`Term_ρ: S × H → {0,1}`；`B_ρ = (K_max, t_max)`。

**定义 469（角色类型与能力闭包）**
```
type_ρ(a, s) = 1  ⇔  a ∈ Act_ρ(s)
Act_ρ ⊆ A_base   （A_base 为基座策略声明的控制空间）
```
角色词表只能从 `A_base` 中做子集选择；任何角色都不能引入基座策略没有声明的动作类型、控制空间或执行器。

**定义 470（候选角色与活动角色）**
```
Assign(ℓ, o) = {ρ ∈ R : ρ 的预注册触发条件与语言/场景一致}
r_t ∈ R，且在承诺窗口内唯一、分段常量
```
`|Assign|=0 ⇒ ⊥`（不执行角色约束，退回基座）；`|Assign|=1 ⇒` 承诺角色；`|Assign|>1 ⇒` 进入定义 482 的交集语义。

**定义 471（角色一致轨迹）**
轨迹 `τ = (s₀,a₀,r₀,…,s_T)` 角色一致，当且仅当：
```
(1) ∀t, ∃! r_t
(2) ∀t, a_t ∈ Act_{r_t}(s_t)
(3) r_{t+1} ≠ r_t  ⇒  RHC(r_t→r_{t+1}) 有效
(4) ref_{t+1} = ref_t  ∨  ReGround(ref_t) 通过
(5) C 含 Barrier 动作 ⇒ |C|=1 ∧ 独立校验签名存在
```

**定义 472（角色漂移）**
```
D_auth = max_t 1[a_t ∉ Act_{r_t}(s_t)]
D_arm  = max_t 1[arm_role(a_t) ≠ α_{r_t}]
D_ref  = max_t 1[ref_t ≠ ref_{t-1} ∧ ¬ReGround]
D_time = max_t 1[t > Term_{r_t}(s_t)]
D_role = w_auth·D_auth + w_arm·D_arm + w_ref·D_ref + w_time·D_time
```
硬安全版要求四个分量全为 0；软审计版用加权和，但 `D_auth` 与 `D_arm` 始终是硬约束。

**定义 473（角色承诺窗口与角色块长）**
```
W_ρ = min(K_declared, ⌊ε_role/δ_role⌋, ⌊ε_vis/δ_vis⌋, B_ρ.K_max)
```
`K_declared` 来自 `metadata.action_chunk_size`。角色块 `(ρ,C)` 满足 `|C| ≤ W_ρ`；块内不得换角；若含 `Barrier` 动作，则 `|C|=1`。超过窗口的部分用保持动作填充，保持挑战接口的长度契约。

**定义 474（角色交接证书 RHC）**
```
RHC(r→r') = (h_s, Post_r(s), Pre_r'(s), g, E, v, σ)
```
有效当且仅当：
```
Post_r(s) ∧ Pre_r'(s)
∧ (g_t = g_{t'} ∨ ReGround(g) 通过)
∧ Fresh(E, t) ≤ τ_e
∧ v ∉ {r, r'}  ∧  Verify_σ(h_s)
```
`h_s` 是状态摘要；`g` 是指代映射；`E` 是证据时间戳；`v` 是独立校验者（独立检查器或独立角色，不与被验角色共享可变状态）。

**定义 475（角色一致性证书 RCC）**
```
RCC(C) = (r_seq, auth_ok, obl_ok, ref_ok, handoff_ok, D_role, Debt)
```
有效当且仅当 `auth_ok ∧ obl_ok ∧ ref_ok ∧ handoff_ok ∧ D_role ≤ ε_role ∧ Debt ≤ D_max`。无效时只允许执行**最后有效前缀**，而不是整块盲执行。

**定义 476（角色证据义务）**
```
Ev_ρ = (freshness_ρ, modality_ρ, cert_ρ)
```
示例：`grasp` 要求腕部相机目标 track、夹爪状态与目标位姿；`place` 要求支撑面位姿与“物体仍在夹爪中”的证据；`bimanual` 要求双腕视角、臂角色状态与力/力矩；`recover` 要求最后有效前缀与无碰撞退避走廊。证据不满足时，角色不能声明完成，也不能交接。

**定义 477（角色屏障）**
```
Barrier = {a : irreversible(a)} ∪ {r→r' : 需要独立验证的高风险交接}
```
屏障动作包括夹爪闭合、物体释放、双手交接、放置到不稳定支撑面等。屏障处角色冻结、`K=1`、先验证后继续；任何角色不得在屏障内部静默切换。

**定义 478（角色覆盖账本）**
```
L(r, r', c) = 公开任务上证书通过的 (r→r') 在上下文层 c 的执行次数
cov(r,r',c) = L(r,r',c) / n_req
Debt(r,r',c) = max(0, n_req − L(r,r',c))
Debt = Σ_{r,r',c} w_c · Debt(r,r',c)
```
`c` 可取对象类、场景类、双臂/单臂、可见/遮挡等层；`w_c` 由安全关键度预注册。

**定义 479（隐藏角色组合与未覆盖质量）**
```
π = (ρ₁,…,ρ_m) 为角色脚本；P_pub, P_hidden 为其分布
Δ_TV = ½ Σ_π |P_pub(π) − P_hidden(π)|
δ_unc = Σ_{π : ¬Covered(π)} P_hidden(π)
```
实际不可直接观测 `P_hidden`，用公开任务与隐藏任务的角色 bigram 经验分布作为可观测代理；`δ_unc` 是本轮要显式报告的隐藏风险量。

**定义 480（角色条件共形校准）**
对角色 `r` 的校准样本 `{(x_i,y_i)}`，非一致性分数 `s_i = score(x_i,y_i)`：
```
q_r^α = Quantile_{⌈(n_r+1)(1−α)⌉/n_r}(s₁,…,s_{n_r})
Pred_r(x) = {y : s(x,y) ≤ q_r^α}
```
在角色层内可交换且 `n_r ≥ n_min` 时，`P(y ∈ Pred_r(x)) ≥ 1−α`。角色条件化是必要的：把抓取与放置混在一个全局阈值里会系统性欠覆盖稀有角色。

**定义 481（层次回退阈值）**
```
q_r^α = q_r^α                                    if n_r ≥ n_min
       = λ·q_r^α + (1−λ)·q_parent^α,  λ = n_r/(n_r+n_min)   otherwise
```
无父层时回退全局 `q_0^α`。回退的覆盖缺口由角色层与父层的 TV 距离 `Δ_r` 控制；报告时必须标记「覆盖未认证」，不能把回退阈值伪装成角色级保证。

**定义 482（歧义交集语义）**
```
Act_amb(R_amb) = ∩_{ρ ∈ R_amb} Act_ρ
```
若为空，输出 `⊥`（保持/弃权）。性质：任何 `a ∈ Act_amb(R_amb)` 都同时属于每个候选角色的可采纳集，因此**无论真实角色是哪一个，执行都不会越权**。代价是交集可能严格小于任一角色，保守性可量化。

**定义 483（UniBot 角色一致得分）**
官方榜单以平均成功率与步骤分为主；内部优化目标定义为：
```
S_RC = (1/|E|) Σ_{e∈E} success_e
       + λ_step · StepScore
       − λ_s · RoleSafetyViolations
       − λ_b · BudgetOverrun
s.t. RCC(C_e)=valid 对所有执行的块
```
`λ_step, λ_s, λ_b` 预注册；最终同时报告官方成功率、步骤分与角色归因失败率，避免用内部目标替代官方指标。

**定义 484（角色一致性与歧义预算）**
```
ε_role = 每 episode 允许的软漂移率上界
ε_amb  = 允许的歧义步比例上界
```
超过 `ε_amb` 时强制进入交集语义/保守原语；超过 `ε_role` 时停止角色切换并冻结到当前角色。

**定义 485（权限泄漏率）**
```
L_auth(π) = (1/T) Σ_t 1[a_t ∉ Act_{r_t}(s_t)]
```
目标恒为 0；非零不是“权衡”，而是类型系统或接口实现有 bug。

**定义 486（指代持续）**
```
g_t : Ref → ObjectTrack
Stable(g_t, g_{t-1}) ⇔ ID(g_t)=ID(g_{t-1}) ∧ ||pose(g_t)−pose(g_{t-1})|| ≤ ε_ref
```
指代不稳定时必须重新接地并生成 `ReGround` 证书；否则交接证书无效。

**定义 487（角色退化算子）**
```
Deg(RC) =
  WR4                      若 RoleCompiler/RoleMonitor/HandoffVerifier 不可用
  safe_prefix(C) + hold    若 RCC(C) 无效
  keep(r_t)                若 RHC(r_t→r') 无效
  global_conformal         若 n_r < n_min 且无父层
```
退化算子必须满足：`Act(Deg(RC)) ⊆ Act(WR4)`，即退化只可能减少动作，不可能新增动作。

```python
# IP-334 RoleCompiler
class RoleCompiler:
    def __init__(self, registry, parser):
        self.registry = registry          # 预注册角色词表 R
        self.parser = parser              # 类型化语言/场景解析器

    def compile(self, instruction, obs):
        """返回候选角色集合；绝不返回自由动作。"""
        trigger = self.parser.parse(instruction, obs)  # 技能族/对象类/臂线索
        if trigger is None:
            return set()                  # 不可接地 -> 退回基座
        candidates = {
            r for r in self.registry
            if r.matches(trigger) and r.pre(obs)
        }
        return candidates                 # 0/1/多 个候选

# IP-335 RoleMonitor
class RoleMonitor:
    def __init__(self, base_metadata):
        self.metadata = base_metadata
        self.role_state = None

    def check_chunk(self, chunk, candidates, obs):
        if not candidates:
            return RCC.bypass()           # 退回 WR v4

        # 定义 482：歧义时只执行所有候选角色的交集
        act = intersect_acts(candidates)
        if act.is_empty():
            return RCC.abstain("empty_intersection")

        violations = []
        for t, a in enumerate(chunk.actions):
            if not act.admits(a, obs):
                violations.append(("authority", t, a))
            if not arm_role_ok(a, candidates, obs):
                violations.append(("arm_role", t, a))
            if not referent_stable(a, obs):
                violations.append(("referent", t, a))
        auth_ok = not any(v[0] == "authority" for v in violations)
        arm_ok  = not any(v[0] == "arm_role" for v in violations)
        ref_ok  = not any(v[0] == "referent" for v in violations)
        return RCC(
            role_seq=chunk.role_seq,
            auth_ok=auth_ok,
            obl_ok=check_evidence(candidates, obs),
            ref_ok=ref_ok,
            handoff_ok=chunk.handoff_ok,
            D_role=soft_drift(violations),
            Debt=ledger.debt(candidates),
        )

    def safe_prefix_pad(self, chunk, violation_index, k_declared):
        """截断到最后有效前缀，用保持动作补足声明块长。"""
        safe = chunk.actions[:violation_index]
        hold = make_hold_action(chunk.actions[violation_index - 1])
        return chunk.replace_actions(safe + [hold] * (k_declared - len(safe)))

# IP-336 HandoffVerifier
class HandoffVerifier:
    def verify(self, r_from, r_to, state, obs, evidence):
        return (
            r_from.post(state, obs)
            and r_to.pre(state, obs)
            and (referent_persistent(r_from, r_to, obs)
                 or reground(r_from, r_to, obs).ok)
            and evidence.fresh(within=TAU_E)
            and self.independent_checker.verify(state, evidence)
        )

# IP-337 UniBot-Role-Adapter
class UniBotRoleAdapter:
    def __init__(self, base_policy, compiler, monitor, handoff, ledger, conformal):
        self.base = base_policy
        self.metadata = base_policy.metadata   # 原样透传，含 token 与 action_chunk_size
        self.compiler = compiler
        self.monitor = monitor
        self.handoff = handoff
        self.ledger = ledger
        self.conformal = conformal

    def get_action(self, obs):
        candidates = self.compiler.compile(obs["observation.language"], obs)
        chunk = self.base.get_action(obs)      # 保留 meta.token 与动作键

        # 角色边界：先验证交接，再允许块进入新角色
        if self.monitor.at_role_boundary(obs):
            if not self.handoff.verify(
                    self.monitor.current_role, candidates,
                    obs, self.monitor.evidence):
                return self._hold_or_previous(obs, chunk)

        cert = self.monitor.check_chunk(chunk, candidates, obs)
        if not cert.auth_ok or not cert.arm_ok or not cert.ref_ok:
            chunk = self.monitor.safe_prefix_pad(
                chunk, cert.first_violation_index, self.metadata["action_chunk_size"])

        self.ledger.update(candidates, obs, cert)
        self.monitor.update(candidates, obs, cert)
        return chunk

    def reset(self):
        self.base.reset()
        self.monitor.reset()
        self.ledger.reset_episode()

# IP-338/339 覆盖债与校准
class RoleCoverageLedger:
    def update(self, roles, obs, cert):
        for r in roles:
            for r_next in self.monitor.reachable(r):
                self.L[(r, r_next, context(obs))] += int(cert.ok)

    def debt(self, roles):
        return sum(max(0, N_REQ - self.L[(r, r2, c)])
                   for r in roles for r2 in self.reachable(r)
                   for c in CONTEXTS)

class RoleConformal:
    def threshold(self, role, alpha):
        n = len(self.scores[role])
        if n >= N_MIN:
            return finite_sample_quantile(self.scores[role], alpha)
        if role.parent is not None:
            lam = n / (n + N_MIN)
            return lam * finite_sample_quantile(self.scores[role], alpha) \
                 + (1 - lam) * self.threshold(role.parent, alpha)
        return self.global_threshold(alpha)   # 明确标记 uncertified

# IP-340 RC-8C 主闭环
def instructgauge_rc(M, s, ell=None):
    # 1. W：世界证据（继承 WR v4）
    world = M.wrg.gather(s)

    # 2. R：角色编译（新增）
    candidates = M.role_compiler.compile(ell, world.obs)

    # 3. C：角色条件化分块规划（继承 IAC，块长受 W_ρ 约束）
    C = M.iac.plan_chunk(candidates, world.hypotheses,
                         M.tools, M.budget(s),
                         M.drift_bound(s),
                         k_max=min(W_rho(r) for r in candidates) if candidates else None)

    # 4. E：执行块（继承 WR v4 的 CVC / SpatialCert）
    cert_wr, executed = M.wrc.execute(C, world)

    # 5. Spatial-C：时空一致性（继承第 4 轮）
    spatial = M.wristcam.spatial_cert(executed, C.psi_post)

    # 6. Role-C：角色一致性（新增）
    rcc = M.role_monitor.check_chunk(executed, candidates, world.obs)

    # 7. V：验证与交接
    if rcc.invalid:
        executed = M.role_monitor.safe_prefix_pad(executed, rcc.first_violation)
    if M.role_monitor.at_role_boundary(world.obs):
        if not M.handoff.verify(M.role_monitor.current_role,
                                candidates, world.obs, spatial.evidence):
            executed = M.role_monitor.keep_previous(executed)

    # 8. U：账本、校准与主张绑定
    M.ledger.update(candidates, world.obs, rcc)
    M.conformal.update(candidates, executed)
    claims = bind_claims(executed, candidates, spatial, rcc)
    return executed, rcc, spatial, claims
```

## 4. 推导

**引理 63（角色过滤器 / 权限非泄漏）** 若 `RCC(C)` 有效，则块 `C` 的每个动作都属于活动角色的 `Act_ρ`，且 `Act_ρ ⊆ A_base`；因此 `L_auth(C)=0`，角色层不可能扩张基座策略的能力。证明：由定义 468–471、475、485 直接展开；对块内动作逐项归纳，`auth_ok` 是每个动作的合取条件。

**引理 64（交接可靠性）** 若 `RHC(r→r')` 有效，且 `r'` 的首个动作满足 `Pre_{r'}`，则交接后的执行仍满足角色一致性；若 `RHC` 无效，监控器只能保持当前角色或回退到上一个认证前缀，不存在静默换角。证明：由定义 474 的有效性合取（后置、前置、指代、证据、独立校验）与定义 471 的换角条件直接得到；无效时由 `Deg` 的 `keep(r_t)` 分支保证。

**引理 65（分块下的角色漂移界）** 在没有交接的单个角色块内，若每步语义/指代漂移不超过 `δ_role`，则 `D_role(C) ≤ |C|·δ_role`；在屏障处漂移被强制重置为 0。因此取 `W_ρ = ⌊ε_role/δ_role⌋` 可使块内漂移不超过预算；不可逆屏障取 `|C|=1` 使漂移不超过单步 `δ_role`。证明：对漂移分量逐项用三角不等式/最大值归纳；屏障动作的 `K=1` 与独立校验使窗口长度为 1。

**引理 66（交集语义的权限安全性）** 对任意候选集 `R_amb`，若 `a ∈ Act_amb(R_amb)`，则对所有 `ρ ∈ R_amb` 都有 `a ∈ Act_ρ`；因此交集语义下执行的动作不可能违反任何候选角色的权限。其代价是 `Act_amb` 可能为空或严格小于每个 `Act_ρ`，即歧义只会减少能力、不会增加风险。证明：由集合交的定义直接得到；空交集由 `⊥` 分支处理。

**引理 67（角色条件覆盖）** 在角色层内可交换且 `n_r ≥ n_min` 时，定义 480 的角色条件共形阈值满足 `P(s_{n+1} ≤ q_r^α) ≥ 1−α`。使用定义 481 的层次回退时，若角色层与父层的分布 TV 距离为 `Δ_r`，则覆盖至少为 `1−α−Δ_r`；`Δ_r` 必须显式报告。证明：前段是 split conformal 的标准有限样本结论；后段用 TV 距离对事件概率做传输不等式。

**引理 68（覆盖—成功核算）** 设隐藏角色脚本 `π` 的每个角色转移在账本中的覆盖债为 0（即每个转移至少有 `n_req` 个公开认证样本），且覆盖层内的角色条件成功下界为 `s_min`；若公开与隐藏的覆盖层内角色转移可交换，则 `E_{P_hidden}[success | π 被覆盖] ≥ s_min·(1−α)`。未覆盖脚本的质量 `δ_unc` 不被该界覆盖，必须作为显式风险单独报告。证明：对脚本上的角色转移用全期望公式，逐转移代入引理 67 的覆盖下界，再用 `s_min` 取下界；未覆盖部分由 `δ_unc` 单独计入。

**引理 69（严格退化）** 关闭角色层时，RC 包装器原样返回基座块，等价于 WR v4；RCC 无效时返回安全前缀 + 保持填充，动作集是 WR v4 可采纳动作的子集；RHC 无效时保持当前角色或回退认证前缀，同样不引入新动作。因此 `Act(Deg(RC)) ⊆ Act(WR4)`。证明：按 `Deg` 的四个分支逐一检查，每个分支要么是恒等，要么是截断/保持/回退，均为子集操作。

**命题 70（角色闭包的任务代价 / 负结果）** 对任何有限预注册角色词表 `R` 与动作模式，存在一个 UniBot 风格的隐藏任务 `T*`，其最优角色脚本需要 `R` 之外的技能或角色转移；严格 RCC 会拒绝 `T*`（候选集为空或交集为空），因此存在正的成功率差距。故角色一致性本身不能保证隐藏任务成功，必须配合开放集角色发现、覆盖债驱动的保守松弛或人工兜底。证明：构造一个需要“未见过的双手交接顺序 + 新对象类别”的任务；由定义 469–470，`Assign` 返回空集，`Deg` 退回基座或弃权，而一个不受角色词表约束的策略仍可能完成该任务，差距由构造保证。

**可证伪预测**：
1. 若角色层只是过滤器，权限泄漏率应在所有公开任务上**恰好为 0**；任何非零都说明实现/类型系统有 bug，而不是可接受的权衡。
2. 交集语义应降低歧义任务的成功率、但消除角色归因的安全违规；若它在无歧义任务上也大量触发，说明角色编译器过触发。
3. 覆盖债应与隐藏任务上的角色归因失败正相关；若无关，说明账本分层选错了上下文。
4. 步骤分回退应 ≤5%；若更大，说明保持填充过于激进，需要更细的块长/重规划策略。

| E479 | 冷启动/稀有角色回退 | 未见角色覆盖率与「未认证」标记一致性；无虚假覆盖声明 |
| E480 | 覆盖债 vs 隐藏成功 | 公开→隐藏对象/背景/扰动，覆盖债与角色归因失败率的相关系数显著 |
| E481 | UniBot-V1 公开任务 | 包装器 vs 基座策略：平均成功率、步骤分；成功率不降，步骤分回退 ≤5% |
| E482 | 消融 | 去角色层/去交接/去交集/去分层校准，分别量化权限泄漏、交接失败、隐藏组合失败 |
| E483 | 不可逆屏障 | 夹爪闭合、释放、双手交接：跨屏障的多步块 0 次；屏障前独立校验 100% |
| E484 | 对抗语言/角色注入 | 「忽略角色」「直接释放」等注入下，权限不扩张；越权动作 0 次 |
| E485 | 延迟与步骤分 | 包装器增量 p99 <2ms；步骤分回退 ≤5%；超时率不增加 |
| E486 | 跨机器人一致性 | N 台机器人上角色分布 TV ≤0.1；成功率方差 ≤0.1 |

## 7. 预注册判据

| 判据 | 门槛（预注册） | 若未达标的处置 |
|---|---|---|
| 权限泄漏（E473/E484） | `L_auth = 0` | 视为类型系统 bug，停止实验并修复；不接受“用性能换安全” |
| 交接假接受（E474/E475） | ≤1% | 收紧交接证书/增加独立校验，不允许静默换角 |
| 漂移检测（E476） | ≤1 个动作块 | 缩短角色承诺窗口 `W_ρ` 或提高监控频率 |
| 角色覆盖（E478） | 每角色 ≥90%（α=0.1，n≥200） | 扩充分层校准数据；不足则回退并标记未认证 |
| 隐藏任务成功（E480/E481） | ≥基座成功率的 85%，且角色归因安全违规为 0 | 降低角色闭包强度，进入交集/保守模式，或增加开放集角色 |
| 步骤分（E481/E485） | 回退 ≤5% | 优化保持填充/重规划，禁止用长保持换取表面安全 |
| 跨机器人（E486） | 角色分布 TV ≤0.1 | 增加机器人层校准或按机器人回退父层阈值 |
| 负结果（E488） | 必须报告，不得隐藏 | 若严格 RCC 明显劣于基座，则把角色层降级为可选审计，不进入主路径 |

## 8. 本轮最大风险

**一句话**：角色一致性可能把「按剧本演得一致」误当成「任务做对」——在 UniBot 的隐藏任务分布下，最危险的不是角色漂移，而是角色本身选错却全程一致地执行；角色闭包越强，对未见角色组合的适应性越差，最终可能在安全证书齐全的情况下稳定地失败。
