### 第 8 轮灵感驱动研究记录

**灵感词**：主动交互、通用机器人平台

**继承关系**：第 7 轮 EFA-v7（IP-501~IP-504）在 CADVS-v6 的「指令-几何-力学三元凿」与七硬门之上，建立了「需求-意图-一致性三角桥」：DIM 推断 ρ_demand、DRC 用 LLM 推理链量化 η_demand、DAC 用面部表情调制 η_affect，系统开始从「被动接受指令」转向「主动推导意图」。本轮延续「在线证书链不新增硬门、只做收紧」原则，聚焦两个新维度：**「何时该主动开口/主动行动」（主动交互）** 与 **「如何把同一份证书安全搬到异构本体上」（通用机器人平台）**。新增 IP-505 PIM、IP-506 EACC、IP-507 PCT、IP-508 EFA-v8；`kc_demand` 与新增 `kc_platform` 重新定位为「部署期准入守卫」，不进入七硬门在线链。

**直觉与动机**：

1. **主动交互 → 从「被动等待」到「价值驱动的开口」**。直觉上，一个可靠的助手既不是每件事都等指令，也不是一直唠叨；它只在「猜错代价高、而问一句很便宜」时开口。严谨地说，引入**主动交互管理器（Proactive Interaction Manager, PIM）**，动作空间 `A_pro = {EXEC, ASK, OFFER, WAIT}`。用决策裕度 `m_t = min_i(s_i - τ_i)` 刻画「当前最优证书离硬门边界有多近」，用需求后验熵 `u_t = H(ρ_demand)/log d_demand` 刻画「我们有多不确定用户要什么」；仅当 `m_t < τ_margin` 或 `u_t > τ_u` 时才考虑主动动作，并用信息价值 `VoI_t = E_z[ΔRisk] - c_ask` 判断是否值得问。关键洞见：**主动交互只能「收缩」执行集**——ASK/OFFER/WAIT 不执行任何轨迹，EXEC 必须取自 EFA-v7 已认证集合，因此新增主动性在结构上不可能扩大 `Exec` 集。

2. **通用机器人平台 → 从「单具身证书」到「可迁移能力契约」**。直觉上，同一句「把杯子递给我」在机械臂、移动底盘、人形上是三种执行，但它们共享「能力语义」。严谨地说，为每个具身定义**能力契约（Embodiment-Agnostic Capability Contract, EACC）** `C = (S, Pre, Post, Res, G)`：技能集、前置/后置条件、资源包络（负载、臂展、自由度、速度、力矩）、硬门配置。用仿真关系 `φ: A → B` 定义子契约 `C_A ⊑_φ C_B`，并用**平台证书迁移算子（Platform Certificate Transfer, PCT）** `T_{A→B}`：仅当子契约成立且门限不放松时返回迁移证书，否则返回 `⊥`（fail-closed）。关键洞见：**平台通用性 = 证书可迁移性，而不是策略同构**——我们不需要一个网络跑遍所有本体，只需要证书的语义在迁移中不被悄悄削弱。

3. **交叉：主动交互是跨具身迁移的「探针」**。直觉上，当证书迁移到新平台、某些前置条件无法在本地确认时，最安全的动作不是硬试，而是主动向用户/上层声明能力缺口并请求确认。严谨地说，迁移后若平台一致性 `c_plat < τ_plat`，PIM 进入「能力校准」模式，优先 `OFFER/ASK` 而非 `EXEC`；平台收紧因子 `η_plat = 1 + λ(1 - c_plat) ∈ [1, 1+ε]` 只用于抬高门限。关键洞见：**把「不确定能不能做」从沉默的冒险，转成显式的、可审计的交互**。

**关键洞见**：第 7 轮回答「如何从用户需求推导行为」；第 8 轮回答「何时该主动开口/主动行动，以及如何把证书安全迁移到异构平台」。七硬门 `kc_evidence_forged_v5` 记号原样复用；在线软因子链只收紧不放松。本轮新增的只有：

- IP-505 PIM（主动交互管理器，价值驱动 + 交互预算）；
- IP-506 EACC（具身无关能力契约）；
- IP-507 PCT（平台证书迁移算子，fail-closed）；
- IP-508 EFA-v8（七硬门 + 软因子链 + 主动仲裁 + 平台守卫）。

**形式化目标（增量）**：

1. **PIM（Proactive Interaction Manager）**：<br>
   - 动作空间 `A_pro = {EXEC, ASK, OFFER, WAIT}`；<br>
   - 触发条件：`m_t < τ_margin ∨ u_t > τ_u`；<br>
   - 信息价值：`VoI_t = E_{z∼Z}[Risk(s_t) - Risk(s_t | z)] - c_ask`，仅当 `VoI_t > 0` 才 ASK；<br>
   - 交互预算：`B_{t+1} = clip(B_t - c_act·1[proactive] + r_success, 0, B_max)`；<br>
   - 安全不变量：`EXEC ⇒ x ∈ E_v7`；`ASK/OFFER/WAIT ⇒ 不执行任何轨迹`，故 `Exec_v8 ⊆ Exec_v7`。

2. **EACC（Embodiment-Agnostic Capability Contract）**：<br>
   - `C = (S, Pre, Post, Res, G)`，其中 `Res = (payload, reach, dof, v_max, τ_max)`；<br>
   - 仿真关系 `φ: A → B` 需满足 `Pre_B(φ(a)) ⊇ φ(Pre_A(a))`、`Post_B(φ(a)) ⊇ φ(Post_A(a))`、`Res_B(φ(a)) ≤ Res_A(a)`（逐分量）；<br>
   - 子契约：`C_A ⊑_φ C_B ⇔ 上述三式成立 ∧ G_B ⪰ G_A`（B 的门限不放松）；<br>
   - 平台一致性：`c_plat = 1 - d_norm(C_A, C_B) ∈ [0,1]`，`d_norm` 为资源/几何归一化差距。

3. **PCT（Platform Certificate Transfer）**：<br>
   - `T_{A→B}(cert) = cert' if C_A ⊑_φ C_B else ⊥`；<br>
   - 迁移证书携带 `(origin, target, φ, 子契约见证, 门限差)`，可离线审计；<br>
   - `⊥` 时禁止部署，必须回到目标本体重新认证（fail-closed）。

4. **EFA-v8（七硬门 + 软因子链 + 主动仲裁 + 平台守卫）**：<br>
   - `ECS_v8 = ECS_v7 · η_plat · η_pro`，其中 `η_plat ∈ [1, 1+ε]` 只收紧，`η_pro` 为主动交互收益的软排序项（不进入阈值）；<br>
   - `τ_i^v8 = γ_i · τ_i^v7 · η_plat`，`η_plat = 1 + λ(1 - c_plat)`，设计上限仍为 1.3；<br>
   - 部署期准入守卫 `kc_platform: T_{A→B}(cert) ≠ ⊥`，与 `kc_demand` 一样位于在线证书链之外。

5. **形式化定义**：给定指令 `L`、目标 `ρ_target`、记忆 `M`、当前具身 `E`：<br>
   - `(ok, x_v7, tag) = EFA-v7.select(L, t_now, context; threshold_scale=η_plat)`；<br>
   - `E = {x_v7}` 若 `ok`，否则 `E = ∅`；<br>
   - `(act, x_exec) = PIM.decide(context, E, u_t, m_t, B_t, risk_class)`；<br>
   - 若 `c_plat < τ_plat ∧ act = EXEC`：强制降级为 `OFFER`；<br>
   - 仅当 `act = EXEC` 时返回 `x_exec`，否则返回 `(False, None, 'PROACTIVE_' + act)`。

**本轮最大风险**：**能力契约的可迁移性假设**——我们假设具身差异可以被 `(S, Pre, Post, Res, G)` 这套符号契约充分刻画，但真实平台的接触动力学、传感器盲区、关节柔顺性往往是隐性的、难以写成前置条件；于是证书可能在符号层面通过子契约检查、却在目标本体上不安全，而「主动交互」会把这个隐性不安全放大成一次自信的公开承诺。

## 2. 关键算法骨架

### IP-505 PIM：价值驱动的主动交互

```python
@dataclass
class ProactiveInteractionManager:
    """PIM：在 {EXEC, ASK, OFFER, WAIT} 间仲裁。
    安全不变量：只有 EXEC 会执行轨迹，且 x ∈ E_v7；
    ASK/OFFER/WAIT 一律不执行，故 Exec_v8 ⊆ Exec_v7。"""
    tau_margin: float = 0.15
    tau_u: float = 0.6
    c_ask: float = 0.2
    c_offer: float = 0.1
    B_max: float = 3.0
    replenish: float = 0.25
    r_offer: float = 0.9  # OFFER 需要的风险等级

    def decide(self, ctx, E_v7, u_t, m_t, B_t, risk_class):
        # 1. 自信且远离门限：直接执行已认证轨迹
        if m_t >= self.tau_margin and u_t <= self.tau_u and E_v7:
            return "EXEC", max(E_v7, key=ctx.utility)

        # 2. 预算不足：宁可等待或执行最保守的安全解，也不打扰用户
        if B_t < self.c_ask:
            if E_v7:
                return "EXEC", min(E_v7, key=ctx.risk)
            return "WAIT", None

        # 3. 计算信息价值，决定是否值得问
        voi = self.value_of_information(ctx, u_t, m_t)
        if voi > self.c_ask:
            return "ASK", None

        # 4. 高风险场景：先提议、等确认，再执行（仍不直接执行）
        if risk_class >= self.r_offer and B_t >= self.c_offer and E_v7:
            return "OFFER", max(E_v7, key=ctx.utility)

        return "WAIT", None

    def value_of_information(self, ctx, u_t, m_t) -> float:
        """VoI = 澄清后期望风险下降 - 提问成本；用 DIM 后验近似。"""
        risk_now = ctx.risk_of(ctx.current_best)
        risk_after = ctx.expected_risk_after_clarification(u_t, m_t)
        return (risk_now - risk_after) - self.c_ask

    def update_budget(self, B_t: float, proactive: bool, success: bool) -> float:
        delta = (-self.c_ask if proactive else 0.0) + (self.replenish if success else 0.0)
        return max(0.0, min(self.B_max, B_t + delta))
```

### IP-506 EACC：具身无关能力契约

```python
@dataclass(frozen=True)
class ResourceBounds:
    payload: float
    reach: float
    dof: int
    v_max: float
    tau_max: float

    def leq(self, other: "ResourceBounds") -> bool:
        return (self.payload <= other.payload and self.reach <= other.reach
                and self.dof <= other.dof and self.v_max <= other.v_max
                and self.tau_max <= other.tau_max)

@dataclass(frozen=True)
class CapabilityContract:
    skills: frozenset[str]
    pre: dict[str, Predicate]
    post: dict[str, Predicate]
    res: ResourceBounds
    gate_profile: "GateProfile"   # 七硬门阈值 + 软因子上限

def subsumes(C_A: CapabilityContract, C_B: CapabilityContract, phi) -> bool:
    """C_A ⊑_φ C_B：B 至少覆盖 A 的技能、前置更弱、后置更强、资源更紧、门限不放松。"""
    mapped = {phi(s) for s in C_A.skills}
    if not mapped <= C_B.skills:
        return False
    for s in C_A.skills:
        sB = phi(s)
        if not implies(C_B.pre[sB], phi(C_A.pre[s])):   # Pre_B ⊇ Pre_A
            return False
        if not implies(phi(C_A.post[s]), C_B.post[sB]): # Post_B ⊇ Post_A
            return False
    if not C_B.res.leq(C_A.res):                        # Res_B ≤ Res_A
        return False
    if not gate_profile_dominates(C_B.gate_profile, C_A.gate_profile):
        return False
    return True
```

### IP-507 PCT：平台证书迁移算子

```python
@dataclass
class PlatformCertificateTransfer:
    """PCT：证书跨具身迁移，fail-closed。"""
    registry: "EmbodimentRegistry"

    def transfer(self, cert, C_A, C_B, phi):
        if not subsumes(C_A, C_B, phi):
            return None                     # ⊥：拒绝部署，回目标本体重认证
        witness = {
            "origin": C_A, "target": C_B, "phi": phi,
            "res_gap": resource_gap(C_A.res, C_B.res),
            "gate_gap": gate_gap(C_B.gate_profile, C_A.gate_profile),
        }
        return MigratedCert(policy=phi(cert.policy),
                            proof=compose_simulation(cert.proof, phi),
                            witness=witness)
```

### IP-508 EFA-v8：七硬门 + 软因子链 + 主动仲裁 + 平台守卫

```python
@dataclass
class EvidenceForgingAssemblerV8:
    """EFA-v8：在线七硬门不变；平台因子只收紧；主动交互只收缩执行集。"""
    v7: EvidenceForgingAssemblerV7
    pim: ProactiveInteractionManager
    eacc: "EmbodimentRegistry"
    tau_plat: float = 0.85
    lambda_plat: float = 0.3

    def select(self, L, t_now, context):
        # 1. 平台一致性（部署期已算，在线只读缓存）
        c_plat = self.eacc.conformance(context.embodiment, context.task)
        eta_plat = 1.0 + self.lambda_plat * (1.0 - c_plat)  # ∈ [1, 1.3]

        # 2. v7 证书：平台因子只抬高门限
        ok, x_v7, tag = self.v7.select(L, t_now, context, threshold_scale=eta_plat)
        E_v7 = [x_v7] if ok else []

        # 3. 决策裕度与需求不确定性
        m_t = self._margin(x_v7, context) if ok else 0.0
        u_t = self._demand_entropy(context)

        # 4. 主动仲裁
        act, x_exec = self.pim.decide(context, E_v7, u_t, m_t,
                                      context.budget, context.risk_class)

        # 5. 能力校准模式：迁移后未确认，则禁止直接 EXEC
        if c_plat < self.tau_plat and act == "EXEC":
            act, x_exec = "OFFER", x_exec

        # 6. 预算结算
        context.budget = self.pim.update_budget(
            context.budget, proactive=(act != "EXEC"), success=(act == "EXEC"))

        if act != "EXEC":
            return False, None, f"PROACTIVE_{act}"
        return True, x_exec, "FORGED_CGE_V8"

    def _margin(self, x, context) -> float:
        s = self.v7.hard_gate_scores(x, context)
        tau = self.v7.hard_gate_thresholds(context)
        return min(s[i] - tau[i] for i in range(len(tau)))

    def _demand_entropy(self, context) -> float:
        return self.v7.dim.posterior_entropy(context) / math.log(self.v7.dim.d_demand)
```

### 集成流水线（v7 → v8）

```
离线/慢时域：
  EACC 契约库（天级）：为每类具身采集能力包络 → 形式化 Pre/Post/Res/G
  PCT 迁移验证（小时级）：对候选 (A,B,φ) 跑子契约检查 + 门限支配检查
  PIM 校准（小时级）：离线日志估计 VoI、c_ask/c_offer、预算补充率
  联邦下发：契约库、迁移见证、PIM 配置、τ_plat → 站内签名分发

部署期（一次性）：
  kc_platform: T_{A→B}(cert) ≠ ⊥，否则拒绝部署并回目标本体重认证
  kc_demand  : η_demand ≥ τ_demand（沿用第 7 轮）

在线准入（亚秒级）：
  EFA-v7.select(threshold_scale=η_plat) ──▶ E_v7（fail-closed）
  PIM.decide(E_v7, u_t, m_t, B_t, risk_class) ──▶ {EXEC, ASK, OFFER, WAIT}
  若 c_plat < τ_plat 且 act = EXEC：降级为 OFFER
  仅 EXEC 执行 x_exec；其余只记录交互意图，不动作

在线控制环（目标 < 0.8 ms）：
  七硬门调用链不变（v7 缓存复用）；PIM 为 O(1) 决策；
  η_plat 与 c_plat 均为部署期缓存，在线零额外开销
```

## 3. 复杂度分析（增量更新）

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 | 实时性指标 |
|---|---|---|---|---|
| PIM.decide | O(\|E_v7\| log \|E_v7\|) | O(1) | \|E_v7\| ≤ 3 | < 0.02 ms |
| PIM.value_of_information | O(d_demand) | O(1) | d_demand=128 | < 0.05 ms |
| EACC.subsumes | O(\|S\|·\|Pre\|) | O(\|S\|) | \|S\| ≤ 32 | 离线 |
| PCT.transfer | O(\|S\|·\|Pre\| + \|proof\|) | O(\|proof\|) | — | 离线 |
| EFA-v8.select 增量 | O(1) | O(1) | 复用 v7 | < 0.1 ms |

**端到端在线增量**：PIM + 平台因子读取 < 0.1 ms；七硬门链路与 v7 一致；总 P99 维持 ≈ 0.8 ms。EACC/PCT 全部离线，不进入实时路径。

## 4. 正确性论证（增量更新）

### 定理 13（主动交互的安全性单调）

**陈述**：设 `Exec_v7` 为 EFA-v7 认证通过的轨迹集合，`Exec_v8` 为 EFA-v8 实际执行的轨迹集合，则 `Exec_v8 ⊆ Exec_v7`。

**证明**：EFA-v8 仅通过 `v7.select(threshold_scale=η_plat)` 产生候选集 `E_v7`，且 `η_plat ≥ 1` 只会抬高门限，故 `E_v7 ⊆ Exec_v7`。PIM 的 `EXEC` 分支返回的 `x_exec` 必属 `E_v7`；`ASK/OFFER/WAIT` 分支均返回 `None` 且不触发执行。能力校准降级只会把 `EXEC` 变为 `OFFER`。因此任何被执行的轨迹都属于 `Exec_v7`，即 `Exec_v8 ⊆ Exec_v7`。∎

### 定理 14（平台证书迁移的可靠性）

**陈述**：若 `C_A ⊑_φ C_B`、`G_B ⪰ G_A`（门限不放松）、且 `φ` 为仿真关系，则对任意在 A 上被七硬门认证的轨迹 `x`，`φ(x)` 在 B 上同样通过七硬门。

**证明**：七硬门本质是状态/动作上的不变式谓词（碰撞、力/力矩、可达性、拓扑连通等）。`φ` 的仿真关系保证 `Pre_B(φ(a)) ⊇ φ(Pre_A(a))` 与 `Post_B(φ(a)) ⊇ φ(Post_A(a))`，即 A 上的前置条件在 B 上仍成立、B 的后置条件不弱于 A 的结论；`Res_B ≤ Res_A` 保证资源约束不会因本体更强而反向失效；`G_B ⪰ G_A` 保证阈值不放松。逐条硬门谓词在 `φ` 下保持，故 `φ(x)` 仍满足全部七门。∎

### 定理 15（主动交互频率的有界性）

**陈述**：在预算动力学 `B_{t+1}=clip(B_t - c_act·1[pro] + r_success, 0, B_max)` 下，任意长度 `W` 的窗口内主动动作次数满足 `N_pro(W) ≤ B_max/c_act + (r_success/c_act)·W`；当用户持续负反馈（`r_success=0`）时，主动率随预算耗尽趋于 0。

**证明**：每次主动动作使预算至少下降 `c_act`，补充最多 `r_success`；预算下界为 0，故窗口内主动次数受初始预算与累计补充约束，即得上界。若 `r_success=0`，预算单调不增，至多 `⌈B_max/c_act⌉` 次主动动作后无法再触发 ASK/OFFER，主动率趋于 0。∎

### 诚实声明

- EACC 的 `Pre/Post` 只能覆盖「可符号化」的能力，接触动力学、柔顺性、传感器盲区等隐性差异不在契约内，定理 14 的结论以「硬门谓词可由 φ 保持」为前提；
- PIM 的 `VoI` 依赖对用户澄清后风险下降的估计，该估计本身可能偏差，导致「该问不问」或「不该问却问」；
- `c_plat` 的归一化距离是工程近似，阈值 `τ_plat` 需按平台族校准；
- 主动交互引入了新的社会性风险（打扰、过度自信、隐私），这些不在硬门语义内，只能靠预算与审计缓解。

## 5. 实验设计与验证计划（仿真 → 实机）

### 5.1 实验设计（MuJoCo 3.x + MJX，平台动物园）

- **平台族**：UR10e 机械臂（6DOF）、移动底盘（2DOF）+ 升降、简化人形（12DOF）、以及两种「能力缺口」变体（低负载、短臂展）。
- **EACC 契约库**：为每类平台标注 `S/Pre/Post/Res/G`；构造 40 组 `(A,B,φ)` 迁移对，其中 12 组故意不满足子契约（用于验证 fail-closed）。
- **数据集**：
  - PIM：10k 条交互日志，标注「何时提问/提议会提升任务成功率且不引起反感」；
  - 迁移：每平台 2k 条已认证轨迹 + 硬门通过标签；
  - 主动提议：500 条高风险场景（易碎物、人机共处、时间压力）。
- **对照**：v7-full、v8-full、消融 A21（无 PIM，永远 EXEC）、A22（无预算，无限主动）、A23（无 EACC，逐平台重训）、A24（强制迁移，忽略子契约）、A25（η_plat 关闭）。
- **场景**：
  - (a) 主动澄清：指令「把东西放到合适的地方」→ 裕度低 + 熵高 → ASK，而非猜测执行；
  - (b) 主动提议：检测到物体将滑落 → OFFER「需要我扶一下吗」，确认后走 v7 证书；
  - (c) 跨具身迁移：UR10e 认证的抓取策略迁移到移动底盘 + 升降，检查七门保持；
  - (d) 平台不匹配：低负载变体请求迁移 → `T_{A→B}=⊥`，拒绝部署（fail-closed）；
  - (e) 交互过载：连续模糊指令下预算耗尽 → 主动率下降，验证定理 15；
  - (f) 能力校准：迁移后 `c_plat < τ_plat` → 强制 OFFER，禁止直接 EXEC。
- **指标**：主动交互精确率（被接受/被接受+被拒）、无谓打扰率、任务成功率、迁移后七门通过率、迁移不可靠率（应恒为 0）、P99 控制延迟、用户满意度。

## 7. 本轮最大风险（最终确认）

**一句话**：**能力契约的可迁移性假设**——我们假设具身差异可以被 `(S, Pre, Post, Res, G)` 充分刻画，但真实平台的接触动力学、传感器盲区、关节柔顺性往往是隐性的；证书可能在符号层面通过子契约检查、却在目标本体上不安全，而「主动交互」会把这个隐性不安全放大成一次自信的公开承诺。
