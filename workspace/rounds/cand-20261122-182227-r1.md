# 第 3 轮（新灵感循环第 1 轮；本轮灵感：「用户共创」×「双足机器人」）

> **基线**：第 2 轮产出 MetricVoiceGauge-NCD-HUTDH-v20 + IP-420–424（联邦感知层）。
> 本轮纪律：**共创是授权选择，不是安全证明；双足安全是轨迹管，不是单点避碰**。不推倒 v20：v20 的 PCA/CTS/CFC/HPC/CFCtrl 全部保留。本轮只做一件事：**把“用户共创的意图”与“双足机器人的动态可行性”安全地编译进证书体系**，产出 v21。

## 0. 直觉与动机

**灵感 1（用户共创 → 人共创目标，不共创证明）**
直觉：用户共创的典型形态是——终端用户演示一段动作、护理者用自然语言纠正“慢一点、别碰桌子”、操作员勾选“这条路径可以”、家属否决“不要靠近楼梯”。传统做法把这些输入当成奖励项或软约束，交给优化器“折中”；但用户是非专家、会前后矛盾、甚至可能恶意，而**安全不能投票**。核心创新：**共创意图编译器 (Co-Creation Intent Compiler, CIC)**。它把异构输入编译成三元组 `(K_veto, π_U, A)`：`K_veto` 是**只增不减的否决集**，`π_U` 是**只用于选择、不用于授权**的偏好序，`A` 是**上下文声明**（地面摩擦、负载、是否有人）。关键反直觉点：**共创不增加任何安全动作，它只是在“已经被证明安全”的动作里做选择**；单个用户可以随时否决，但再多的用户也不能“投票放行”一个未被证书覆盖的动作——**安全不是民主，是否决的民主**。一句话：**人可以共创目标与上下文，不能共创证明**。

**灵感 2（双足机器人 → 安全是整条轨迹管，不是一个点）**
直觉：双足机器人是欠驱动、接触丰富的系统；为了躲开桌角而迈出的一步，可能恰好把质心推出支撑域，于是“避碰成功、然后摔倒”。更根本的是，**摔倒本身就是一次剧烈碰撞**（躯干/头部撞地）。传统做法把“脚 placement 的静态避碰”和“平衡控制器”分开做，但二者强耦合。核心创新：**双足可行性证书 (Bipedal Viability Certificate, BVC)**。给定显式**接触调度** `σ`（哪条腿在什么时段接触地面/物体），把“有意的支撑接触”从碰撞中豁免，把**调度之外的一切接触——包括摔倒——都判定为碰撞**；于是“零碰撞”和“不摔倒”被统一成同一张证书。证书覆盖的是**整条轨迹的不变管 (invariant tube)**，而非终点或单个构型。关键反直觉点：**最安全的一步往往不是离障碍最远的一步，而是留在可行性管内的那一步**；避碰裕度与动态可行性此消彼长，证书必须在可行集内优化，而不是先最大化间隙再看平衡。

**灵感 3（二者如何耦合 → 一份可撤销的共创契约）**
直觉：用户提供**意图**和**上下文假设**，机器人提供**动作证明**；这天然是一份契约：机器人承诺“动作留在可行性管内”，用户共同签署“上下文假设成立”。核心创新：**共创可行性契约 (Co-Creation Viability Contract, CVC)**。用户声明不被信任，而是被编译成**稳健上下文包络** `𝒜(A)`；为避免用户把包络“收窄”到错误值，`𝒜(A)` 与**机载传感器先验包络**做**并（join）**——用户只能让包络更宽（更保守），不能让它窄于传感器先验。契约在假设监控器确认包络仍覆盖真实上下文时有效；一旦越界或过期，立即撤销并回退 v20。关键反直觉点：**共创的安全性不来自“相信用户”，而来自“用户无论如何都无法把安全集撑大”**——错误的用户声明最多降低活性，不能制造授权。

**三者如何统一**
统一为 **v20 证书体系之上的“意图×可行性”层**：v20 回答“给定几何与感知，节点 n 在 θ 下是否零碰撞”；v21 回答“在用户想要的动作里，哪些同时满足双足动态可行、且其上下文契约仍然成立”。CIC 是意图侧（异构输入→单调约束束），BVC 是可行性侧（接触调度→轨迹管证书），CVC 是契约侧（假设可撤销、越界回退）。共享状态 `ζ_co = (K_veto, π_U, A, 𝒜(A), σ, T, trust, contract_valid, mode_co)`。统一接口：**若 CIC 的否决、BVC 的轨迹管、CVC 的假设监控三者同时通过，则 `Select_{π_U}` 在 `(Θ_col ∩ Θ_via) \ K_veto` 上选出计划；否则退回 v20 的保守路径或安全停。**

## 1. 研究问题（轮次升级版）

- **Q1（异构共创输入的单调编译）**：如何把演示、纠正、自然语言、否决、偏好排名、上下文声明统一编译成 `(K_veto, π_U, A)`，并保证“任何输入都只能收缩或重排、不能扩张”认证集？当多个用户冲突时，如何用**否决民主 + 信任格**消解而不产生振荡或策略性操纵？

- **Q2（双足可行性与碰撞的联合证书）**：如何定义接触调度 `σ` 下的可行性核 `Θ_n^via(o,σ)` 与不变管 `T`，使 BVC 同时覆盖“无意碰撞”与“摔倒”？如何把 v20 的 CCV 从末端/单点扩展到**全身扫掠体积**，并正确豁免有意支撑接触？跨步态、跨接触调度如何组合证书？

- **Q3（上下文假设的稳健化与可撤销）**：如何把用户上下文声明转成**与传感器先验并（join）的稳健包络**，使得错误声明只能缩小安全集？假设监控器如何在 500–1000Hz 控制环内检测越界（摩擦突变、负载偏移、地形可变形）并及时撤销契约？

- **Q4（低频率共创与高频率控制的时序协调）**：用户更新约 0.1–1Hz，双足控制约 500–1000Hz，BVC 重认证介于两者之间；如何保证两次用户更新之间轨迹管始终有效？如何在“契约已过期但尚未重认证”的窗口里维持可验证安全（回退 v20 还是安全停）？

## 2. 设计原则（在 P31–P33 基础上新增 P34–P36）

**P34 共创单向授权律（Co-Creation Monotone Authorization）**
设用户贡献集合 `U`，编译得到否决集 `K_veto(U)`、偏好序 `π_U`、上下文包络 `𝒜(A)`。认证集定义为 `Θ_n^cert(U) = (Θ_n^col ∩ Θ_n^via) \ K_veto(U)`，执行计划为 `Select_{π_U}(Θ_n^cert(U))`。要求：`K_veto` 对 `U` 单调不减（多一个否决只会多删，不会少删）；`Select` 是幂等选择算子，值域含于输入集；**任何 `u ∈ U` 都不能使 `Θ_n^cert` 增大**。因此 `Exec_v21 ⊆ Exec_v20`，且“多数用户同意”不构成授权，**只有证书构成授权**。

**P35 双足可行性管律（Bipedal Viability Tube）**
给定接触调度 `σ = {(link_i, env_j, [t_i^-, t_i^+])}`，定义有意接触集 `C_int(σ)`。轨迹 `q(t)` 的**无意碰撞指示** `Col_un(q) = 1` 当且仅当存在 `t` 使某 link 与环境发生 `∉ C_int(σ)` 的接触或穿透。定义可行性谓词 `Via(q,σ)`：质心/捕获点动力学满足支撑多边形、摩擦锥与 CoP 有界，且存在恢复控制使捕获点留在可恢复集内。BVC 仅在**整条不变管** `T(θ,σ) ⊆ V_n^via(o,σ)` 且 `∀q∈T: Col_un(q)=0` 时签发。**摔倒即 `Col_un`**，与碰撞同判。

**P36 假设契约可撤销律（Revocable Assumption Contract）**
用户上下文声明 `A` 编译为包络 `𝒜_user(A)`，与传感器先验包络 `𝒜_sensor` 取**并**：`𝒜(A) = 𝒜_user(A) ⊔ 𝒜_sensor`（并=更宽=更保守）。可行性核按 `∩_{a∈𝒜(A)} V(a)` 的**最坏情况**计算；包络过宽导致核为空则拒绝签发。契约 `C = (O_robot, O_user, 𝒜(A), τ_c)` 仅在 `τ_c` 内、且监控器观测 `a* ∈ 𝒜(A)` 时有效；越界、过期或传感器失效即撤销，回退 v20 安全停/保守路径。**用户只能加宽包络，不能收窄到传感器先验之下**。

## 3. 与基线的接口（如何退化）

- CIC 失效（无用户输入/编译器不可用）⇒ 采用默认偏好 `π_0`，无否决集 ⇒ 退化为 v20 的默认选择（仍受 BVC 约束）；
- BVC 失效（可行性核不可计算/超时）⇒ 只做 v20 的静态 CCV 碰撞检查 + 安全停 ⇒ 等价 v20（更保守）；
- CVC 失效（假设监控器不可用/包络越界）⇒ 撤销契约，回退 v20 保守路径或安全停；
- 三者全失效 ⇒ 完全回退 v20；
- **安全继承**：`K_veto` 只删、`Select` 只选、`Θ_via` 只交、`𝒜(A)` 只宽，四者任意失效都使认证集收敛性增强，`Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19` 由引理 162 保证。

## 4. 预期贡献

1. **共创意图的单调编译**：首次把演示/纠正/自然语言/否决/偏好/上下文统一为“只收缩、只重排、不扩张”的约束束，给出“安全是否决的民主”这一可证明的授权不对称性；
2. **双足可行性证书**：把“碰撞安全”与“动态平衡”统一为接触调度下的轨迹管证书，证明“摔倒=无意接触”，使双足避碰不再与平衡控制割裂；
3. **可撤销的共创契约**：给出用户上下文声明与传感器先验“并包络”的稳健化方法，使错误或恶意声明最多降低活性、无法扩大安全集；
4. **全身扫掠碰撞扩展**：把 v20 CCV 从单点/末端扩展到摆动腿、手臂、躯干的全身扫掠体积，并正确豁免有意支撑接触；
5. **意图×可行性闭环**：CIC+BVC+CVC 落在 v20 之上，形成“用户想要 → 动态可行 → 假设成立 → 安全执行”的闭环，`Exec_v21 ⊆ Exec_v20`。

## 5. 本轮最大风险

**一句话**：共创契约把上下文假设稳健化为“用户声明 ⊔ 传感器先验”，但若**传感器先验本身与用户声明共享同一个盲区**（例如都假设地面刚性、都忽略地毯/软垫的形变与摩擦突变），则可行性管是在**错误的接触模型**下被签发，机器人可能“契约有效、证书通过、却仍然摔倒”——这是一种**共创出来的假前提**，投票与可行性检查都看不见它。

# IP-425 CoCreationIntentCompiler
class CoCreationIntentCompiler:
    def __init__(self, trust_lattice, default_pref, parser):
        self.trust = trust_lattice
        self.default_pref = default_pref
        self.parser = parser

    def compile(self, contributions, node, obj):
        """
        把异构共创输入编译为单调约束束。
        不变量：任何 kind 都不能使认证集增大。
        """
        veto_terms, pref_terms, attestations = [], [], []

        for u in contributions:
            if not self.trust.admissible(u):
                continue
            if u.kind == "VETO":
                veto_terms.append(self.parser.parse_veto(u, node, obj))
            elif u.kind in ("PREFERENCE", "CORRECTION", "DEMONSTRATION"):
                pref_terms.append((u.trust, self.parser.parse_pref(u, node, obj)))
            elif u.kind == "CONTEXT":
                attestations.append(self.parser.parse_context(u))
            # 其他类型一律忽略：未知输入永不进入证书

        K_veto = monotone_union(veto_terms)      # 只增不减
        pi_U = aggregate_preferences(pref_terms, self.default_pref)
        A = merge_context_claims(attestations)   # 冲突时保留全部声明（更保守）
        return IntentBundle(K_veto=K_veto, pi=pi_U, context=A)

    def select(self, theta_cert, intent):
        """选择算子：只在已认证集合内排序取优，绝不扩张集合。"""
        candidates = theta_cert.difference(intent.K_veto)
        if candidates.is_empty():
            return None, "NO_CERTIFIED_ACTION"
        return argmax_over(candidates, intent.pi), "OK"


# IP-426 CoCreationTrustLattice
class CoCreationTrustLattice:
    def __init__(self, floor=None, byzantine_frac=1.0 / 3.0):
        self.floor = floor or {
            "VETO": 0.0, "CONTEXT": 0.5, "PREFERENCE": 0.3,
            "CORRECTION": 0.4, "DEMONSTRATION": 0.2,
        }
        self.byzantine_frac = byzantine_frac

    def admissible(self, u):
        """否决权对所有人开放；放行类贡献必须有可验证来源与足够信任。"""
        if u.kind == "VETO":
            return u.provenance.verified
        return (u.provenance.verified
                and u.trust >= self.floor.get(u.kind, 1.0))

    def resolve(self, contributions):
        """否决民主 + 加权中位序：少数否决即成立，多数不能放行。"""
        vetoes = [u for u in contributions if u.kind == "VETO"]
        prefs = [u for u in contributions if u.kind != "VETO"]
        K_veto = monotone_union([self.parse_veto(u) for u in vetoes])
        pi = weighted_median_order(prefs)   # 中位序抗极端值/策略操纵
        return K_veto, pi

class BipedalViabilityCertifier:
    def __init__(self, capture_model, ccv_ext, horizon=2.0, dt=0.005):
        self.capture = capture_model
        self.ccv_ext = ccv_ext
        self.H = horizon
        self.dt = dt

    def viability_kernel(self, node, obj, ctx_env, sigma):
        """对上下文包络取最坏情况交集：包络越宽，核越小。"""
        kernel = None
        for a in ctx_env.samples():
            V = self._kernel_single(node, obj, a, sigma)
            kernel = V if kernel is None else intersect(V, kernel)
            if kernel.is_empty():
                return kernel
        return kernel

        recover = self.capture.recoverable_set(support, a.mu, a.slope)

        tube = self.forward_tube(node, theta, sigma, ctx_env, self.H)
        if not tube.subset_of(K):
            return None, "VIABILITY_TUBE_ESCAPE"

        # 整条管上都不允许无意接触；摔倒即无意接触
        if not self.ccv_ext.swept_safe(node, obj, tube, sigma):
            return None, "UNINTENDED_CONTACT"

        return ViabilityCertificate(
            sigma=sigma, tube=tube, kernel=K,
            ctx_env=ctx_env, proof=self._proof(tube, K),
        ), "OK"

class WholeBodySweptCollisionExtender:

# IP-429 CoCreationViabilityContract
class CoCreationViabilityContract:
    def __init__(self, monitor, ttl_context=0.5):
        self.monitor = monitor
        self.ttl_context = ttl_context

    def form(self, intent, cert, user_ids):
        # 关键：用户包络与传感器先验并，用户只能加宽，不能收窄
        A = join_envelopes(intent.context, self.monitor.sensor_prior())
        obligations = {
            "robot": ("stay_in_tube", cert.tube),
            "users": ("hold_context", A),
        }
        signatures = [self.monitor.sign(uid, A) for uid in user_ids]
        return Contract(obligations, A, signatures,
                        t_valid=now() + self.ttl_context)

    def is_valid(self, contract, observed_ctx):
        if now() > contract.t_valid:
            return False, "CONTRACT_EXPIRED"
        if not contract.A.contains(observed_ctx):
            return False, "ASSUMPTION_VIOLATED"
        if not all(s.verified for s in contract.signatures):
            return False, "UNSIGNED_ASSUMPTION"
        return True, "OK"

class ViabilityFreshnessMonitor:
    def __init__(self, aps, control_hz=500, certify_hz=20):
        self.aps = aps
        self.dt = 1.0 / control_hz
        self.certify_dt = 1.0 / certify_hz

    def tick(self, contract, cert, observed_ctx):
        ok, reason = contract.is_valid(observed_ctx)
        if not ok:
            # 撤销契约：回退 v20 安全停/保守路径

            return self.aps.fallback(mode="V20_SAFE_STOP",
                                     reason="TUBE_ESCAPE")
        return self.aps.execute_within(cert.tube, margin_col_fed=0.0)

## 3. 推导

**引理 157（共创单向授权）** `K_veto(U)` 对 `U` 单调不减，`Select_{π_U}` 幂等且值域含于输入集，`Θ_n^via` 只做交集。故 `Θ_n^cert(U) = (Θ_n^col ∩ Θ_n^via) \ K_veto(U) ⊆ Θ_n^col`，且任意新增 `u` 都不能使 `Θ_n^cert` 增大，从而 `Exec_v21 ⊆ Exec_v20`。推论：**多数同意不是授权，证书才是授权**。∎

**引理 158（接触意图分离）** 由定义，`Col_un(q)=1` 当且仅当存在 `∉ C_int(σ)` 的接触或穿透；摔倒的躯干/头部接地必然 `∉ C_int(σ)`，故 `fall(q) ⟹ Col_un(q)=1`。WSCE 仅在整条管上 `Col_un=0` 时返回真，因此 BVC 签发同时蕴含 v20 意义上的无意碰撞安全与不摔倒。∎

**引理 159（可行性管不变性）** 若 `T(θ,σ) ⊆ V_n^via(o,σ)`，且实际扰动落在模型界内，则管上任意状态在恢复控制下捕获点保持在可恢复集内，即 `Via` 对整段执行时域成立。∎（依赖捕获点模型与扰动界，见风险 2/3）

**引理 160（并包络稳健性）** 契约取 `𝒜(A) = 𝒜_user(A) ⊔ 𝒜_sensor ⊇ 𝒜_sensor`，核按 `∩_{a∈𝒜(A)} V(a)` 计算，故 `∩_{a∈𝒜(A)} V(a) ⊆ ∩_{a∈𝒜_sensor} V(a)`。若真实上下文 `a* ∈ 𝒜_sensor`，则 `a* ∈ 𝒜(A)`，证书对 `a*` 成立。用户无法把包络收窄到传感器先验之下（错误收窄被 join 覆盖），错误加宽只会缩小核、降低活性。∎

**引理 161（契约可撤销与时序安全）** 每个控制拍检查 `C` 有效性与管包含性；任一失败即回退 v20 安全停。回退期间不执行未认证动作，且 v20 的安全性由引理 151–156 继承。故两次重认证之间不存在“已过期但仍执行”的不安全窗口。∎

**引理 162（v21 整体安全继承）** 在同一几何快照、同一用户集合、同一传感器先验下，`Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19 ⊆ Exec_v18`。证明：CIC 只删/只选、BVC 只交可行性核、CVC 只加宽包络并附撤销条件、VFM 越界即回退，四者叠加只能产生子集。∎

## 7. 已知风险与失效模式

1. **共创假前提（最大风险）**：`𝒜(A)=𝒜_user ⊔ 𝒜_sensor` 只能防“用户收窄”，不能防“用户与传感器共享盲区”。若地面是可变形地毯、软垫或湿滑涂层，而先验模型仍假设刚性平面 + 定摩擦，则可行性管在错误接触模型下签发，机器人可能“契约有效、证书通过、仍然摔倒”。缓解：引入在线接触模型辨识（足底力/IMU/视觉形变）、把未建模柔顺性显式并入包络、对未知地形强制降速与扩大管。

2. **可行性核过度保守**：捕获点/质心模型忽略手臂摆动、躯干扭转与脚部滚动，导致核偏小、证书几乎全拒。缓解：分层模型（LIPM 粗筛 + 全身 QP 精验）、按步态缓存核、对保守度做在线标定。

3. **接触调度脆弱**：实际打滑、提前触地或意外支撑会使 `σ` 失效，导致管频繁撤销、活性骤降。缓解：调度容错（允许 `C_int` 的邻域接触）、接触事件在线重规划、把打滑概率并入扰动界。

4. **信任格被俘获/合谋**：否决权对所有人开放，恶意用户可大量否决造成“拒绝服务”。缓解：否决需可验证来源、按用户分组限额、对否决做可解释审计；安全上仍只会更保守，不会更危险。

5. **偏好聚合的策略操纵**：用户可能谎报偏好以影响 `Select`。缓解：加权中位序、按历史一致性更新信任、对极端排名做稳健统计。

6. **全身扫掠的计算爆炸**：`N_samples·N_links·CCV` 在 500Hz 下可能超预算。缓解：分层扫掠（粗包络 + 局部精检）、增量更新、GPU 并行、只在重认证拍做全量。

7. **包络过宽导致持续回退**：传感器先验若过宽（如未知摩擦），`𝒜(A)` 过宽使核为空，系统长期停在 v20 安全停。缓解：主动探测（轻踏/试探步）、在线辨识、对已知地形缓存先验。

## 8. 本轮最大风险

**一句话**：共创契约用“用户声明 ⊔ 传感器先验”来保证用户无法撑大安全集，但若**传感器先验本身与用户声明共享同一个未建模盲区**（如都假设地面刚性、都忽略柔顺性与摩擦突变），则双足可行性管会在错误的接触模型下被签发，机器人可能“契约有效、证书通过、却仍然摔倒”——这是一种**共创出来的假前提**，否决投票与可行性检查都看不见它。
