# 第 1 轮（新灵感循环；本轮灵感：「多端口部署」×「个性化交互」）

> **基线**：上一循环末版 MetricVoiceGauge-NCD-HUTDH v15（IP-378–401；定义 607–626；引理 125–130；实验 E661–E670）。
> 本轮纪律：**一次认证、按端口侵蚀、按用户侵蚀、合成即安全**。不推倒 v15：v13 的 AIO/CPD/DDL/RTCR、v14 的 SCD/DSD/DCA/EDC、更早的 v8–v12 九不变式全部保留。四个新组件——CTO（证书传输算子，含 `U_port`）、CAF（核—适配器分解）、PEN（个性化包络，含 `U_user`）、MCC（多端口分层共形校准，含组条件覆盖）——一律以**中立元**接入，失效即严格退回 v15（引理 132），再沿 v15→v14→…→v8 退化。本轮只做三件事：把"部署"从复制代码改写为**证书的保距传输**、把"个性化"从改写目标函数改写为**在已认证集合内的选择**、把二者合成到同一个"侵蚀格"上。

## 0. 直觉与动机

**灵感 1（多端口部署 → 证书不是复制的，是可传输的）**
直觉：现有系统把 v15 的证书当成"在参考端口上验证一次就到处可用"。这在软件端口上成立，在物理端口上不成立：不同机器人本体、末端、边缘/云运行时端点，甚至不同交互通道（语音/屏/触觉），其动力学、传感延迟、摩擦、执行器饱和、坐标约定都不同。于是"多端口部署"通常退化为两种坏做法：要么每个端口重新做全栈验证（成本 `O(P·全量)`，实际没人做，最后带病上线），要么把参考端口的证书直接复制过去（把端口差异当噪声，安全余量被悄悄吃掉）。
核心创新：**证书传输算子（Certificate Transport Operator, CTO）** 与 **端口间隙 `U_port`**。证书不是布尔标签，而是 `(授权集, 余量函数)` 对；跨端口不做"重新证明目标安全"，而做"证明目标端口至多比参考端口差多少"——用端口差异 `δ_π`（动力学 + 观测 + 延迟）经余量函数的 Lipschitz 常数 `L_h` 传播成一个**确定性侵蚀量** `U_port = L_h(δ_π + δ^o_π) + η_π`，只保留参考证书中余量不小于 `U_port` 的动作。关键反直觉点：**把"证明目标安全"换成"证明目标不比参考更差"，问题就从不可完成的全量重验，变成一个可测、可预算、可单调收缩的量**；证不出来的端口不是被放行，而是被**侵蚀成更小的授权集**。

**灵感 2（个性化交互 → 个性化只改边界内的选择，不改边界）**
直觉：个性化最常见的实现是把用户偏好塞进目标函数（更快、更近、更话多、更拟人），再让同一个安全层去"兜底"。这在平均用户上看起来没问题，但个性化本质上是在**把行为推向安全边界**：越"贴合"的用户，越可能得到越薄的余量。而安全证书恰恰最怕"平均上没事"。更隐蔽的是，用户偏好会随交互自适应，形成用户侧分布漂移，安全层却仍按冷启动分布校准。
核心创新：**个性化包络（Personalization Envelope, PEN）** 与 **个性化间隙 `U_user`**。个性化不进入安全目标，而是作为**已认证集合上的选择器**：先由端口证书给出 `Acc_π`，再按用户请求的"激进程度 / 亲密程度 / 交互频率"计算一个**非负侵蚀量** `U_user(u,x)`，得到 `Env_u = Acc_π ⊖ U_user`；偏好只在 `Env_u` 内选动作。关键反直觉点：**越个性化的用户得到的是越小的集合，而不是越大的权限**；个性化买来的是"同样的安全、不同的风格"，不是"更多的自由"。用户风险预算 `α_u` 只能决定侵蚀多少，不能决定是否侵蚀。

**灵感 3（多端口×个性化 → 侵蚀格与分层合成，而不是 P×U 的笛卡尔积）**
直觉：多端口（P 个）乘个性化（U 个用户）= P×U 组证书，每组都要校准，样本量随乘积爆炸；现实里每个 `(端口, 用户组)` 胞元只有极少数据，于是要么合并（掩盖异质性），要么放宽（制造系统性欠覆盖）。而 P×U 里绝大多数组合从未被访问，为它们预先认证是浪费。
核心创新：**核—适配器分解（Core-Adapter Factorization, CAF）+ 多端口分层共形校准（Multi-Port Conformal Calibrator, MCC）**。把证书拆成与端口无关的**不变核** `K` 与端口相关的**适配器** `A_π`：`K` 只认证一次，每个端口只重验低维适配器；再用**分层共形**（共享核残差 + 端口/用户组残差）替代逐对校准，并对组条件覆盖做多重性修正。于是证书在**侵蚀格**上合成：`Acc_{π,u} = Acc_0 ⊖ U_port(π) ⊖ U_user(u) ⊖ U_cal(π,u)`，侵蚀可交换、可结合、单调。关键反直觉点：**端口与用户不是两个正交的维度，而是同一个"侵蚀预算"的两个扣减项**；预算有限时，正确的做法不是给每个组合单独认证，而是让共享核承担大部分，把端口/用户差异显式记账。

**三者如何统一**
统一为 **v15 之上的部署—交互层**：v15 回答"在参考端口上、对默认用户，哪些动作被允许"，v16 回答"换到端口 π、面对用户 u，这份允许还剩下多少、由谁在包络内选择"。CTO 保距传输并侵蚀 `U_port`；CAF 把重验成本压到适配器维度；PEN 在侵蚀后的集合内做偏好选择并扣减 `U_user`；MCC 用分层共形给出 `U_cal` 与组条件覆盖。共享状态 `ζ_poly=(π,u,G,α_u,U_port,U_user,U_cal,Env_u,mode)`。**CTO 回答"这个端口配不配继承证书"，CAF 回答"继承要重验哪一小块"，PEN 回答"用户能在这个端口的证书里怎么选"，MCC 回答"这个选择对每个用户组还成立吗"**。四者不是四个移植补丁，而是把证书从"单点事实"变成"可传输、可分解、可在包络内个性化"的资源。

## 1. 研究问题（轮次升级版）

- **Q1（证书传输的可证语义）**：如何定义端口差异 `δ_π` 与余量传播，使 `U_port` 是 sound 的（不是经验调参）？当差异由动力学、观测、延迟、执行器限幅共同造成时，Lipschitz 界是否过保守到清空授权集？传输失败时如何退回"端口最小安全策略"，而不是复制参考证书？
- **Q2（个性化与安全的可分性）**：如何把用户偏好与安全边界严格分离？`U_user` 如何由用户请求量（速度/距离/交互频率/拟人度）导出而非手工设定？用户自适应导致偏好漂移时，包络如何保持单调收缩？冷启动用户、少数群体、辅助需求用户的包络如何避免被"平均"掉？
- **Q3（分层校准与公平）**：分层共形（核残差 + 端口/用户组残差）在异质端口与稀疏用户组上是否仍 valid？组条件覆盖需要怎样的多重性修正与样本量？同时覆盖 P 个端口、G 个用户组时，"公平"带来的保守性代价如何定量？能否用加权共形/e-value 降低 Bonferroni 的过度保守？
- **Q4（兼容与活性）**：CAF 的不变核是否真的与端口无关，还是把端口依赖偷藏进核？PEN 是否可能通过 `U_user` 的符号/优先级 bug 放宽授权？`Acc_{π,u} ⊆ Exec_v15` 是否严格？合成后是否因 `U_port+U_user+U_cal` 过大而频繁 `a_ask`、把可用性压到不可接受？新增模块能否守住 50Hz 并严格退回 v15？

## 2. 设计原则（在 P19–P24 基础上新增 P25–P27）

**P25 证书保距传输律（Certificates Transport by Contraction）**
跨端口禁止复制布尔授权；只能传输 `(Acc, m)` 并按 `U_port` 侵蚀。`U_port` 必须由可测的端口差异与显式 Lipschitz 常数给出；测不出/界不住差异的端口，一律不得继承，退回端口最小安全集或重新全量认证。传输只能收缩，不能扩张。

**P26 个性化只弱不强律（Personalization Selects, Never Widens）**
个性化只能在 `Acc_π` 内做选择；`U_user ≥ 0`；`Env_u = Acc_π ⊖ U_user ⊆ Acc_π`。偏好、风险预算、用户画像都不得进入安全阈值的放行侧；任何"为提升体验而放宽阈值"的实现视为违规。用户越激进 ⇒ `U_user` 越大 ⇒ 集合越小。

**P27 分层合成与组条件覆盖律（Hierarchical Composition & Group-Conditional Coverage）**
`U_total = U_port + U_user + U_cal`，授权集按 `⊖` 顺序侵蚀、可交换；`U_cal` 必须来自分层共形，且对每个 `(端口, 用户组)` 胞元给**同时**覆盖（不只看边际）。任一胞元覆盖失效或 `U_total` 超预算，必须**塌缩到不变核的默认包络**并触发重校准，禁止用其他胞元的余量补贴。

## 3. 与基线的接口（如何退化）

- CTO 失效 ⇒ `U_port=0`、只允许参考端口：等价 v15（单端口）；非参考端口直接拒绝继承；
- CAF 失效 ⇒ 无分解，退回每端口全量 v15 认证（成本高但语义等价）；
- PEN 失效 ⇒ `U_user=0`、`Env_u=Acc_π`：个性化关闭，等价 v15 的默认交互；
- MCC 失效 ⇒ `U_cal` 取最保守先验或 `α_g=α/(PG)` 的 Bonferroni，仅失去统计紧致性，不失去 soundness；
- 四者全失效 ⇒ MetricVoiceGauge-NCD-HUTDH v15，再沿 v15→v14→…→v8 退化；
- **安全继承**：`Acc_{π,u} ⊆ Acc_π ⊆ Acc_0 ⊆ Exec_v15`，由引理 132 保证。四模块不能新增授权、不能放宽阈值、不能跳过侵蚀。

## 4. 预期贡献

1. **证书保距传输**：把多端口部署从"复制/重验"二选一改写为可测的侵蚀预算，给出 `U_port` 的 sound 界与失效语义；
2. **核—适配器分解**：把跨端口重验成本从全状态维度降到适配器维度，并给出可检验的"核确实端口无关"判据；
3. **个性化包络**：把个性化从目标函数改写为已认证集合内的选择器，证明"越个性化越保守"，并处理用户漂移、冷启动与跨端口画像一致性；
4. **分层组条件校准**：把"多端口×多用户"从 P×U 组合爆炸改写为共享核 + 分层残差，给出同时覆盖与公平代价；E671–E680 覆盖传输 soundness、侵蚀单调、公平覆盖、端到端与消融。

## 5. 本轮最大风险

**一句话**：`U_port` 只在"`δ_π` 被正确界定"时 sound，而 `δ_π` 往往是在参考工况/新机状态测出来的；个性化又持续把用户推向侵蚀后的边界——当端口在长期磨损、温漂、负载变化中缓慢偏离，用户偏好在自适应中缓慢漂移时，`U_port` 与 `U_user` 会同时偏小，而组条件覆盖仍只在旧校准胞元上成立，系统就在"每个端口都在侵蚀、每个用户都在包络内"的表象下，给某个（磨损端口, 激进用户）组合放行了一个**被双重低估侵蚀的**动作——即**可移植的、个性化的、却已经越界的决定**。

## 1. 关键算法骨架

```python
# IP-402 证书传输算子：按 U_port 把参考端口证书侵蚀到目标端口
class CertificateTransportOperator:
    def __init__(self, ref_cert, L_h, eta_pi, min_safe_policy):
        self.ref = ref_cert              # (Acc_0, m_0)
        self.L_h = L_h                   # 余量函数 Lipschitz 常数
        self.eta_pi = eta_pi             # 端口模型/线性化误差上界
        self.min_safe = min_safe_policy  # 端口物理最小安全策略（停/柔顺/a_ask）

    def transport(self, x, delta_dyn, delta_obs):
        U_port = self.L_h * (delta_dyn + delta_obs) + self.eta_pi
        acc0, m0 = self.ref.at(x)
        acc_pi = {a: m0[a] - U_port for a in acc0 if m0[a] >= U_port}
        if not acc_pi:
            # 侵蚀清空：绝不复制参考证书，退回端口最小安全策略
            return self.min_safe.at(x), U_port, True
        return Certificate(acc_pi), U_port, False


# IP-403 核—适配器分解：不变核一次认证，逐端口只重验适配器
class CoreAdapterFactorization:
    def __init__(self, kernel, adapters, invariant_test):
        self.K = kernel                  # 端口不变核（全局保守下界）
        self.adapters = adapters         # port -> A_pi
        self.invariant_test = invariant_test

    def factor(self, port):
        if port not in self.adapters:
            return None
        if not self.invariant_test(self.K, port):
            # 核不独立：不得假装可移植，诚实退回全量重验
            return None
        return CompositeCertificate(self.K, self.adapters[port])

    def recert_dim(self, port):
        return self.adapters[port].dim   # 重验成本 ≈ 适配器维度，而非全状态


# IP-404 个性化包络：偏好只做集合内选择，U_user 只侵蚀不放宽
class PersonalizationEnvelope:
    def __init__(self, L_pref, psi, alpha_u):
        self.L_pref = L_pref
        self.psi = psi                   # r_u -> 非负侵蚀量，单调不减
        self.alpha_u = alpha_u

    def gap(self, u, x):
        r = min(1.0, max(0.0, u.aggressiveness))
        dev = u.requested_action(x).distance_to(u.reference_action(x))
        return max(0.0, self.psi(r) + self.L_pref * dev)

    def envelope(self, cert_pi, u, x):
        U_user = self.gap(u, x)
        env = {a: m - U_user for a, m in cert_pi.acc.items() if m >= U_user}
        return Envelope(env, fallback=cert_pi.fallback), U_user

    def select(self, env, u, x):
        if not env.acc:
            return env.fallback
        return max(env.acc, key=lambda a: u.utility(a, x))


# IP-405 多端口分层共形校准：组条件覆盖 + 同时覆盖修正
class MultiPortConformalCalibrator:
    def __init__(self, cells, groups, alpha, n_min):
        self.cells = cells
        self.groups = groups
        self.alpha = alpha
        self.n_min = n_min
        self.alpha_g = alpha / (len(cells) * len(groups))  # union bound 同时覆盖
        self.q = {}

    def calibrate(self, residuals):
        for cell in self.cells:
            for g in self.groups:
                res = residuals.get((cell, g), [])
                if len(res) < self.n_min:
                    # 样本不足：用共享核先验，不用其他胞元补贴
                    self.q[(cell, g)] = self.shared_prior(cell)
                else:
                    self.q[(cell, g)] = conformal_quantile(res, self.alpha_g)
        return self.q

    def U_cal(self, port, group):
        return self.q[(port.id, group)]

    def covered(self, port, group):
        return (port.id, group) in self.q


# 主闭环：MetricVoiceGauge-NCD-HUTDH-P v16（多端口个性化版）
def metricvoicegauge_round_16_multiport_personalization(
        M, s, obs, port, user, skill_pool=None, dataset=None, ell=None, ...):
    # ---- v15 主路径原样保留（MW→NGE→HCC→HDT→HATD→NCP→SCD→守卫）----
    results = middleware.run_cycle(runners={...}, ctx=ctx)
    nge.update_belief(obs)
    hcc.update_identification(obs.motor_enc, obs.joint_enc, obs.current)

    # ---- CAF：核—适配器分解（失败即全量重验，语义等价）----
    comp = caf.factor(port)
    ref_cert = comp.certificate() if comp is not None else full_recertify_v15(port)

    # ---- CTO：证书保距传输 ----
    cert_pi, U_port, collapsed = cto.transport(
        obs, port.delta_dyn(), port.delta_obs())
    if collapsed:
        execute(port.min_safe.at(obs))          # 端口最小安全策略
        return M.inherited_v15_path(ctx)

    # ---- PEN：个性化包络（只侵蚀，不放宽）----
    env, U_user = pen.envelope(cert_pi, user, obs)
    a = pen.select(env, user, obs)

    # ---- MCC：分层共形与组条件覆盖 ----
    U_cal = mcc.U_cal(port, user.group)
    if not mcc.covered(port, user.group):
        a = env.fallback                         # 未覆盖胞元：默认包络
    elif env.margin(a) - U_cal < 0:
        a = env.fallback
    else:
        execute(a)

    # ---- 漂移：端口/偏好任一漂移即塌缩到不变核默认包络并重校准 ----
    if port_drift.fired() or pref_drift.fired():
        execute(caf.K.default(obs))
        mcc.calibrate_async(new_obs_buffer)
        ctx.mode = 'collapsed'

    # ---- 跨端口画像一致性：全局包络取端口交集，绝不取并 ----
    if user.has_global_profile and len(ctx.active_ports) > 1:
        env_global = intersect_over_ports(user, ctx.active_ports)
        a = pen.select(env_global, user, obs)

    # ---- v15 继承路径 ----
    return M.inherited_v15_path(ctx)
```

## 2. 推导（引理 131–137）

**引理 131（端口侵蚀的 soundness）** 设参考证书 `(Acc_0,m_0)` 对 `f_0` sound，且余量非收缩：对 `a∈Acc_0`，`m_0(f_0(x,a))≥m_0(x,a)`；`m_0` 为 `L_h`-Lipschitz；目标端口满足 `‖(f_π(x,a),h_π(x))−(f_0(x,a),h_0(x))‖ ≤ δ_π+δ^o_π`，模型误差上界 `η_π`。令 `U_port=L_h(δ_π+δ^o_π)+η_π`，`Acc_π={a∈Acc_0 : m_0(x,a)≥U_port}`，`m_π=m_0−U_port`。则 `Acc_π` 对 `f_π` sound。证明：对 `a∈Acc_π`，由 Lipschitz 与差异界
```
m_0(f_π(x,a)) ≥ m_0(f_0(x,a)) − L_h(δ_π+δ^o_π) − η_π
              ≥ m_0(x,a) − U_port = m_π(x,a) ≥ 0 .
```
故目标端口一步后仍落在参考安全集 `{m_0≥0}` 内；对步数归纳即得不变性。∎ 推论：**传输保守性完全由 `U_port` 决定**；`δ_π` 测得越准，侵蚀越少；测不准时只能取上界，宁可清空也不越界。

**引理 132（侵蚀合成与严格退化）** 对 `U_1,U_2≥0`，
```
(Acc,m)⊖U_1⊖U_2 = (Acc,m)⊖(U_1+U_2),
(Acc,m)⊖(U_1+U_2) ⊆ (Acc,m)⊖U_1 .
```
故 `Acc_{π,u}=Acc_0⊖(U_port+U_user+U_cal) ⊆ Acc_π ⊆ Acc_0 ⊆ Exec_v15`。令四个中立元分别取 `U_port=0 / 无分解 / U_user=0 / U_cal=先验`，即逐项严格退回 v15；四者全关即 v15，再沿 v15→…→v8 退化。证明：逐条代入定义 634，利用 `m−U_1−U_2=(m−U_1)−U_2` 与阈值单调性。∎ 推论：**安全继承不依赖四模块的实现细节，只依赖它们都只是非负侵蚀**；任何会"加回授权"的实现都破坏 `Exec_v16⊆Exec_v15`。

**引理 133（核—适配器分解的充分条件与重验成本）** 若 `m_π=K+A_π`，`K` 是对所有端口 sound 的保守下界（其 soundness 证明不含任何端口参数），且对每个 π 独立验证 `K+A_π` 仍是端口 π 真余量的下界，则复合证书 sound；跨端口重验只涉及 `A_π`，成本 `O(dim A_π)`，而非全状态 `O(dim x+dim a)`。若 `K` 的验证引用了端口参数，或 `A_π` 依赖全局状态而不可局部验证，则分解条件失效，必须退回全量重验。证明：由下界传递性 `K+A_π ≤ m_true^π` 与 `K` 的端口一致性直接得 soundness；成本由被验证对象的维度计数。∎ 推论：**CAF 不是"近似省事"，而是把端口依赖显式隔离到低维适配器**；不可分解就诚实退化，不得把端口参数偷渡进核。

**引理 134（分层组条件覆盖与公平代价）** 在每组 `(π,g)` 内样本可交换，取 Mondrian 水平 `α_g=α/(P·G)`，以核残差分位与胞元残差分位之和作为 `U_cal`。则所有胞元**同时**满足 `P(m_{true} ≥ m̂−U_cal) ≥ 1−α_g` 的概率至少 `1−α`；每胞元所需样本量 `n_{π,g}=Ω(α_g^{−2} log(PG/β))`。仅做边际池化（把所有端口/用户混合校准）只保证边际覆盖，存在少数胞元被系统性欠覆盖而边际指标看起来完美。证明：共形有效性逐胞元成立，再对 `P·G` 个事件取 union bound；样本下界由二项集中不等式/DKW 给出。∎ 推论：**公平不是免费的**：同时覆盖 P×G 个胞元要多付约 `log(PG)` 的样本或相应扩大 `U_cal`；这正是 P27 中 `U_cal` 预算的来源，也是"个别用户被平均掉"的根因。

**引理 135（个性化只弱不强与用户单调性）** 若 `U_user(u,x)≥0` 且对激进程度 `r_u` 单调不减，则
```
Env_u = Acc_π ⊖ U_user(u,·) ⊆ Acc_π ,
r_u ≥ r_{u'}  ⇒  Env_u ⊆ Env_{u'} .
```
且 `select` 在 `Env_u` 内选任意动作都不改变 soundness。证明：由 `⊖` 对 `U` 的单调性；偏好只作用于集合内部的 argmax，不改变集合边界。∎ 推论：**个性化改变的是"在安全集合里选哪个"，不是"集合有多大"**；若产品需求是"更贴合=更自由"，则与 P26 直接冲突，必须显式拒绝而不是偷偷放宽阈值。

**引理 136（多端口个性化三难/预算不等式）** 对任意异质端口与用户组，任何方案必须满足
```
U_total ≥ U_port + U_user + U_cal
        ≥ Ω(δ_π) + ψ(r_u) + Ω(√(log(PG/α)/n)) ,
```
因此在总侵蚀预算 `B` 固定时，不可能同时做到：(i) 零端口重验（`U_port→0`），(ii) 全个性化（`U_user→0` 且 `Env_u→Acc_π`），(iii) 组条件同时覆盖 `1−α` 且样本量 `n=o(log(PG)/α²)`。证明：三项分别由引理 131 的 Lipschitz 传播、PEN 的单调性与引理 134 的共形样本下界给出；取构造性的"大 `δ_π` + 极少样本 + 高 `r_u`"端口/用户对，任一项放松都会使另一项突破 `B` 或破坏覆盖。∎ 推论：**"可移植 + 全个性化 + 公平覆盖 + 零代价"四者不可兼得**；必须显式用 `U_port`、`U_user`、`U_cal`、样本量或 `α` 交换。

**引理 137（跨端口用户画像的一致性）** 设同一用户 u 在端口 `π_1,π_2` 上的包络为 `Env_u^{π_i}=Acc_{π_i}⊖U_user(u)`。若全局画像只在"最强端口"上校准，并把该端口的包络部署到所有端口，则存在 `π_j` 使实际授权超出 `Env_u^{π_j}`。要在所有端口一致，必须取
```
Env_u^global = ⋂_{π∈Π_active} Env_u^π ,
```
或以 `U_user^global = max_π U_port(π) − min_π U_port(π) + U_user` 作保守补偿。证明：由引理 132 的单调性，`U_port` 较大的弱端口授权集更小；把强端口包络直接用于弱端口会破坏子集关系，构造反例即得。∎ 推论：**个性化画像不是跨端口可自由迁移的资产**；可共享的是"偏好表示"，不可共享的是"授权余量"。

## 6. 已知风险与失效模式

1. **`δ_π` 低估**：端口差异只在标称工况/新机状态测量，磨损、温漂、负载、地面材质改变会使其缓慢增大，`U_port` 不再 sound。缓解：在线端口差异估计、保守上界、漂移监控与重测。

2. **`L_h` 全局过大**：为保证 soundness 取全局 Lipschitz 常数，可能使 `U_port` 大到清空授权集，退化为频繁 `a_ask`。缓解：分区域局部 Lipschitz、按动作类别细化、必要时只保留核层。

3. **伪不变核**：CAF 把端口相关项偷藏进 `K`，表面"一次认证到处可用"，实际不可移植。缓解：端口无关性检验（留一端口验证）、核参数冻结、审计。

4. **Bonferroni 过度保守**：同时覆盖 `P·G` 个胞元使 `U_cal` 过大，少数组/小端口几乎不放行。缓解：加权共形、e-value、分层部分池化、按风险分配 `α_g`。

5. **用户偏好漂移/博弈**：自适应个性化把 `r_u` 逐步推向边界，用户也可能学习"怎么要求更多"。缓解：`r_u` 速率限制、包络单调不可逆记录、偏好审计与安全回放。

6. **跨端口画像不一致**：在强端口学到激进画像并迁移到弱端口，导致弱端口越界。缓解：全局交集包络（引理 137）、按端口重新校准偏好表示、禁止迁移授权余量。

7. **冷启动与辅助需求用户样本稀缺**：这些用户组恰是校准最难覆盖的尾部，容易被边际池化"平均掉"。缓解：主动采样、分层预算、默认保守包络、单独覆盖率报告。

8. **隐私与画像共享**：跨端口共享个性化画像可能泄露用户敏感信息。缓解：只共享偏好表示而非原始数据、差分隐私、端口本地化存储。

9. **端口定义过粗**：把动力学差异很大的端点归为同一端口，或把"交互通道 + 本体"混为一个端口，导致 `δ_π` 失真。缓解：端口注册表强制声明差异上界、粗端口拆分、通道级 `δ^o` 单列。

10. **侵蚀实现 bug**：把 `⊖` 写成加法、把带符号 `U` 当预算、或在 `select` 中回写边界，都会静默放宽授权。缓解：属性测试（单调、子集、中立元）、形式化不变量检查、发布前 100% 嵌套校验。

11. **公平—可用性冲突**：为最差组提高覆盖会整体扩大 `U_cal`，拉低所有人可用性，形成"越公平越难用"的政治阻力。缓解：显式预算表、按场景分级 `α`、把公平代价与任务收益同时预注册。

## 7. 本轮最大风险

**一句话**：`U_port` 与 `U_user` 都是"相对参考工况"的保守量，当端口在长期磨损/温漂中缓慢偏离、用户偏好在自适应中缓慢漂移时，两者会同时被低估，而组条件覆盖仍只在旧胞元上成立——系统会在"每个端口都在侵蚀、每个用户都在包络内"的表象下，给某个（磨损端口, 激进用户）组合放行一个**可移植的、个性化的、却已经越界的**决定。
