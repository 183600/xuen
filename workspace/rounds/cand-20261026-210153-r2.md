# 第 8 轮 · TRIO：把 32 个任务压成可迁移的 option 自动机，用因果探针做状态守卫

> 检索/复核日期：**2026-10-26（UTC）**。文中所有 `[S#]` 对应产物区 §14 来源表；除另注外，链接均为 2026-10-26 检索，论文日期以 arXiv/会议页为准。赛事身份不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「迁移学习」「可解释性」「状态机」。我先做了一次证据纠错（下一节），再把三个词各自钉到官方事实和头部方案上，最后合成主判断：**这届比赛缺的不是更大的 VLA，而是“跨任务可复用的 option 库 + 运行时可审计的状态 + 能定位并修复失败的因果信号”；把 32 个任务编译成 14 个 option 的 typed automaton，用 VLA 内部因果探针做转移守卫，用检索到的演示迁移 option 参数，是一条能在单模型约束内落地、且直接对准成功率与 5 个泛化轴的路线。**

## 0. 先纠错：上一轮从榜单步骤分推出的“终局失败”证据不成立

### 0.1 榜单现在显示 8 个模型，但数据仍是脚本生成

`leaderboard.html` 现在确实展示了 8 个模型（检索于 2026-10-26）[S1]：

| 排名 | 模型/用户 | 平均成功率 | 步骤分 |
|---|---|---|---|
| 1 | MolmoAct2 / DexHacker | 29.7% | 39.0 |
| 2 | WALL-OSS-0.5 / Generalist Robotics | 28.5% | 38.9 |
| 3 | DreamZero / World Model Lab | 27.9% | 37.9 |
| 4 | Spirit-v1.5 / VLAGO | 25.9% | 34.4 |
| 5 | DM0 / Embodied AI Institute | 23.5% | 31.7 |
| 6 | PI-0.5 / RoboReasoner | 22.8% | 30.6 |
| 7 | GigaBrain-0 / xembody | 22.6% | 29.5 |
| 8 | GR00T N1.5 / Humanoid Dynamics | 20.5% | 28.1 |

但同一页脚仍然写着「即将发布」，`leaderboard_data.json` 的第一行仍是 `"generated_from": "gen_leaderboard.py"`，详情页视频仍是占位（`runs.html` 也是 Coming Soon）[S1][S8]。所以这 8 行是**演示/种子数据**，不是可引用的真实排名；用户看到的“榜首不到 30%”与页面一致，但只能当“难度先验的弱信号”，不能当结论。

### 0.2 线性拟合揭穿“步骤分 − 成功率 = 终局失败”的推断

上一轮（PILOT）用 8 个模型的“步骤分平均比成功率高约 8.6pp”推断“大部分失败发生在做完大部分步骤、倒在最后一步”。我本轮把 256 条 `task_metrics` 全部拉出来做回归，发现：

```text
step_score ≈ 1.3405 × success_rate + 0.016
R² = 0.9999，最大残差 0.086
```

8 个模型逐任务的 `success_step` 与 `step_score` 也几乎完全共线；换句话说，**占位数据里的步骤分不是独立观测，而是成功率的近似线性变换**。所谓 +8.6pp 的“后段失败”是生成脚本的线性关系，不是真实现象。上一轮据此把“终局放置”定为唯一闸门，证据链需要降级。

这不是说终局放置不重要——**官方评分结构**仍然说明终局步骤是成功闸门、且权重最大；但“多数失败倒在最后一步”这个经验判断，必须用真机调试槽重新验证，不能从占位榜单推出来。

### 0.3 纠错后仍然成立的三个事实

1. **排名规则**（官方手册 1.2，2026-10-26 复核）[S2]：32 任务总平均成功率排序；成功率相同才看总平均步骤分；再相同看提交日期。**成功率是第一目标，步骤分只是 tie-breaker**。上一轮“步骤分约占 60% 权重”的算术不成立。
2. **评测结构**：每任务 10 次，5 类泛化各 2 次（位置、干扰物、背景、未见物品、人为干扰）；单任务 180s；有**不计分单任务调试通道**[S2]。这 5 个轴不是 5 个独立数据集，而是同一任务内的 10 次条件组合——**任何跨轴资产都会同时吃到 5 份收益**。
3. **评分步骤**：32 个任务的 `score_steps` 仍公开（2026-10-24 抓取；2026-10-26 任务页可复核）[S3]。终局步骤合计 1275/3200 ≈ **39.8%**；放置/插入/堆叠/闭合类步骤约 **59.7%**；32 个终局步骤里 28 个是放置类，4 个是拔出/取出/翻转/倾倒类终局操作（T05/T11/T12/T14）。这仍然是“终局操作是成功闸门”的结构性证据，只是不能再用占位榜单的 gap 去量化它。

### 0.4 底座比上一轮更清楚了：WLA 6B、Apache 2.0、LoRA 可训

宇树在 2026-09-28 放出了 **UnifoLM-WLA-1.0-Base**：6B 参数、约 2,500 小时真机数据、单模型 64 任务、支持二指夹爪与多款五指手、Apache 2.0，并提供 action expert 的 LoRA 微调代码[S7]。这比“只能拿一个黑箱 API”强得多：**我们能读到 action expert 的中间层，能在官方数据上做 LoRA，能把探针挂到 policy 内部**。这是本轮“可解释性”从口号变成工程的前提。

数据侧也确认：collection 32 个数据集、约 32k episodes / 169h；HangCup 1,043 条 / 194,564 帧 / 30fps；每条任务的语言字段有 5 条英文复述[S4][S5]。这意味着：

- 32k 条演示足够训练 **option 级**的检索与参数统计，不需要从零训大模型；
- 5 条复述是天然的语言鲁棒性数据，可用于 option prompt 的复述增强；
- 四路 RGB + EE 位姿 + 夹爪 + 30fps，足够做 phase 分割与相对位姿标签。

## 1. 三个灵感词，各自钉到官方事实上

### 1.1 迁移学习：不是“换 embodiment”，是“跨任务/跨轴复用 option 与参数”

这届比赛的单模型约束，把“迁移学习”逼到一个很具体的位置：

- **不能**按任务切模型（规则明确禁止混合多个模型）[S2]；
- **不能**靠评测时微调（评测是远程 API，模型必须提前部署）；
- **能**做的是：把 32 个任务压成少量**共享 option**，让每个 option 吃到多任务数据；把演示里的**相对参数**（容器系释放位姿、插入方向/深度、把手抓取位姿、拉链方向）迁移到当前场景；把探针训练成**跨背景/位置/物体不变**。

这和“预训练一个更大的多 embodiment 模型”不是一回事。头部模型（WALL、GR00T、π0.5）已经证明多 embodiment 预训练有效，但它们的瓶颈不在“没见过 G1”，而在**测试时的状态跟踪与 OOD 恢复**。本轮把迁移学习落在三个可测的地方：

1. **跨任务 option 共享**：14 个 option 覆盖 32 任务，每个 option 的训练数据来自多个任务（例如 `insert` 同时吃 T10 插头、T26 网线、T32 针管、T12 钥匙）；
2. **跨 demonstration 参数迁移**：K 条相似演示的相对位姿统计，而不是复制整段轨迹；
3. **跨泛化轴不变性**：探针在背景/位置/物体替换下保持稳定，才允许当状态守卫。

一句话：**迁移的单位不是“模型”，是“option + 相对参数 + 不变谓词”**。

### 1.2 可解释性：不是“事后画热图”，是“运行时因果守卫”

头部模型里已经有人把“可解释”当卖点：MolmoAct2 的 action reasoning / 空间 embodied reasoning / 自适应深度推理，本质上是在模型内部显式化“看哪里、为什么这么动”[S9]。这说明“可解释”不是研究者的自嗨，而是这届头部方案已经在用的竞争维度。

但“事后给一张热图”对比赛没用。比赛要的是：**在 180s 内，知道当前处于哪一步、上一步是否真的完成、现在是否该重试/回退/换参数**。所以本轮把可解释性定义成三个运行时问题：

- **状态可读**：VLA 的 residual stream 里是否有“已抓稳 / 已插入 / 已拉上 / 被人挪走”的线性可读信号？
- **状态可信**：这个信号是因果的，还是只是与视觉背景相关？必须过反事实、干预、跨轴不变性、校准四道关（CPA）。
- **状态可用**：读出的状态要能驱动自动机的转移/修复，而不只是日志。

这里有两个直接相关的证据：

- **Decoding Task Progress**（2026-08）证明任务进度可以从 VLA representation 线性读出、且能跨任务泛化，但**用它 steering 动作会失败**[S18]。这正好支持“探针做监控/守卫，不做动作生成”的定位。
- **Not All Features Are Created Equal**（ICLR 2026）证明语言探针 >99% 准确，但行为可能完全不看语言；视觉清晰时语言被忽略[S19]。这警告我们：**高准确率的探针可能是 epiphenomenal**，必须做干预敏感性测试，且要把状态显式注入 policy，而不是指望它自己“听懂”。

所以本轮的可解释性不是“加一个 explanation head”，而是 **CPA（Causal Probe Acceptance）+ 状态 token 注入 + 审计轨迹** 三件套。

### 1.3 状态机：不是“加一个 planner”，是“把评分步骤变成可审计的自动机”

头部方案几乎都是 monolithic VLA（MolmoAct2、WALL、Spirit、DM0、π0.5、GR00T），少数是 world model（DreamZero、GigaBrain）。它们没有一个把**显式任务状态**作为一等公民。而 2026 年的分层/长程证据 consistently 指向“显式状态 + 子任务边界”能救长程：

- **Harness VLA**（2026-07）：冻结 VLA + memory-guided agent + 小型 analytic primitive 库，在 LIBERO-Pro 扰动桌面上 +38.6pp（模拟）[S23]；
- **SparkVLA**（2026-08）：stop-aware 分层 + 自适应 chunk，47.12%，比官方基线 +30.57%[S24]；
- **PALM**（CVPR 2026）：affordance + 连续 subtask progress，LIBERO-LONG 91.8%[S30]；
- **ProgVLA**（2026-05）：显式 progress 表示，紧算力下提升长程[S31]；
- **EvoMem-VLA**（2026-10）：状态演化记忆，长程操作[S25]；
- **神经符号 procedural reasoning**（2026-09）：task graph + multimodal memory + perception 验证，是最接近的竞品[S21]。

这些工作共同说明：**长程不是靠“更大的 chunk”解决的，是靠“知道现在在哪、下一步是什么、上一步有没有真的完成”解决的**。但它们大多要么引入运行时 LLM/外部 planner（Harness、ASPIRE、神经符号），要么只做 progress 预测（PALM、ProgVLA），要么只做失败检测（VLA-FAIL、VLA-Corrector）。本轮的状态机走第三条路：

- **离线编译**：用公开 `score_steps` + 语言 + 演示，编译成 typed option automaton；运行时没有 LLM；
- **在线守卫**：用 VLA 内部因果探针 + 几何检查做转移条件；没有第二个人工智能模型；
- **可审计**：每一步的 option、谓词、证据、修复动作都落日志；失败可归因；
- **可回退**：人为干扰备注直接变成 undo 边；状态回归时回退，而不是从头再来。

## 2. 头部 8 个模型在做什么，缺什么

### 2.1 四种 archetype

| archetype | 代表 | 核心 | 对这届比赛的强项 | 缺口 |
|---|---|---|---|---|
| Action reasoning | MolmoAct2 | MolmoER 空间推理 + 自适应深度 + action reasoning | 空间 grounding、可解释 | 没有显式任务状态机；推理不等于恢复 |
| Multi-embodiment pretraining | WALL-OSS-0.5、GR00T N1.5、π0.5 | 大规模跨本体数据 + 双系统/动作专家 | 泛化、语言跟随 | 测试时 OOD 状态跟踪仍弱；无 option 级修复 |
| World model | DreamZero、GigaBrain-0 | 视频/世界模型 + 动作联合预测 | 动态/空间预测、数据生成 | 推理重、实时性差；不直接给任务状态 |
| Data-centric / embodied-native | Spirit-v1.5、DM0 | 干净/多样数据 + 紧凑 VLA | 真机成功率、工程成熟 | 仍是 flat policy；长程/干扰恢复靠数据堆 |

（模型细节见 [S9]–[S16]；榜单分数是占位，不能当真实强弱。）

### 2.2 共同缺口

1. **没有显式状态**：flat VLA 把“当前在第几步、上一步是否完成”隐式编码在 observation 里；一旦人为干扰把已完成步骤撤销，它没有“回退”概念。
2. **没有失败归因**：VLA-FAIL/VLA-Corrector 能检测“不对劲”，但不能回答“是抓错了、放偏了、还是被挪走了”，也就不能选对修复动作。
3. **没有跨任务 option 抽象**：每个任务单独学，32 个任务的数据不能互相放大；而 32 个任务里大量步骤是同构的（抓、搬、放、插、拔、开、关、叠、挂、折、倒）。
4. **没有把“步骤分”变成运行时可用的进度**：评分步骤是公开的，但现有模型没有把它编译成可审计的自动机；progress 预测（PALM/ProgVLA）是连续值，不是离散可验证的步骤完成。
5. **没有把人为干扰备注变成恢复策略**：官方 `generalization` 字段已经把“先叠后撤”“拉上再拉开”“拧回瓶盖”写出来了，但现有方案没有显式 undo 边。

### 2.3 合成榜单的弱信号（只当假设，不当证据）

如果把占位数据当“弱信号”看，逐任务均值最低的是：Plug In Ethernet 17.7、Unlock 20.1、Spell robot 21.8、Organize Stationery 22.5、Open Pill Bottle 22.7、Hang Cup 23.0、Pick Out Battery 23.3、Zip Up 23.4；最高的是 Stack Cups 30.3、Conveyor Food Sorting 29.1、Place Photo Frames 28.0、Paper Cup Stacking 28.0、Store Earphones 27.9。**低分任务集中在插入、关节物体、精细装配、悬挂**，而不是单纯的“长程”。这与“接触丰富终局操作 + 状态跟踪”的判断一致，但因为数据是生成的，只能当假设。

另一个弱信号：不同 archetype 的强项是互补的（DreamZero 在 Place Photo Frame/Hang Cup 高，WALL 在 Remove Pinned Note/Plug Charger 高，GigaBrain 在 Conveyor 高，GR00T 在 Clear Plates 高，Spirit 在 Stack Bowls/Cups 高）。但单模型规则禁止按任务切模型；互补性只能通过**统一架构/蒸馏**吸收，不能做“多模型路由”。本轮不把“多模型集成”作为主路径。

## 3. 失败模型：32 个任务到底难在哪

结合 32 个任务的评分步骤、官方泛化备注、以及 2026 年的失败/恢复文献，我把失败分成五类（不是互斥）：

| # | 失败模式 | 典型任务 | 现有方案的盲点 | TRIO 的对策 |
|---|---|---|---|---|
| F1 | **接触丰富终局**：插不进、拧不开、拉链咬不住、针管推不动 | T10/T12/T14/T19/T23/T26/T31/T32 | flat VLA 没有“插入深度/对齐/力”的显式状态 | `insert`/`articulate`/`pour` option + 几何/探针守卫 + 柔顺重试 |
| F2 | **关节物体/可变形**：盖子、锁、拉链、毛巾、袋子 | T09/T12/T14/T16/T18/T19/T23/T28/T29/T31 | 视觉状态变化细微，chunk 内开环执行 | `articulate`/`fold` + 阶段探针 + 小步闭环 |
| F3 | **长程状态跟踪**：多物体、顺序、计数、已完成步骤 | T15/T17/T20/T21/T22/T25/T27/T31 | 无显式记忆，重复/漏步/早停 | typed automaton + memory + undo 边 |
| F4 | **OOD grounding**：位置/背景/未见物体/干扰物 | 全 32 任务 | 依赖背景/位置 shortcut；语言被视觉淹没 | 关系中心谓词 + 跨轴不变探针 + 相对参数迁移 |
| F5 | **人为干扰恢复**：挪动、撤销、抽走 | T01–T32 的 human_1/human_4 | 检测到异常但不会回退/重做 | 谓词回归检测 + undo/repair + 时间预算 |

这里的关键判断是：**“终局放置”只是 F1 的一部分，不是全部**。上一轮把火力集中在“最后 3 厘米的放置”，方向对，但覆盖不了 T12 的开锁、T14 的拧盖、T19 的拉链、T32 的针管。本轮把“终局操作”扩展成 **contact-rich terminal manipulation**，并用 option 库统一处理。

### 3.1 与 5 个泛化轴的映射

| 泛化轴 | 主要威胁 | TRIO 的对应机制 |
|---|---|---|
| 位置 | 目标/容器偏移，相对位姿失效 | OPT 相对参数迁移；位置不变探针；视觉伺服 |
| 干扰物 | 错误物体绑定、碰撞 | 关系中心谓词；object binding；碰撞/接近检查 |
| 背景 | 视觉 shortcut、探针漂移 | 背景不变探针；CPA 轴不变性；状态 token 降低对背景的依赖 |
| 未见物品 | 语言/外观泛化失败 | option prompt 复述；相对参数不依赖实例；语言 grounding 探针 |
| 人为干扰 | 已完成步骤被撤销、目标被挪走 | 谓词回归检测；undo 边；repair；memory |

## 4. 主判断：TRIO-GPR

### 4.1 一句话

**把 32 个任务编译成 14 个可迁移 option 的 typed automaton；用 VLA 内部因果探针做状态守卫；用 K 条演示的相对参数做 option 迁移；用失败归因驱动 undo/repair；全部跑在一个 6B WLA checkpoint + 确定性代码里。**

### 4.2 三个组件

1. **TOL（Transferable Option Library，可迁移 option 库）**
   14 个 option：`reach`、`grasp`、`lift`、`transport`、`place`、`insert`、`extract`、`articulate`、`hang`、`fold`、`pour`、`press`、`track`、`stabilize`。每个 option 有 typed 参数、前置/后置/失败谓词、修复算子、超时/重试预算。32 个任务 = 14 个 option 的不同组合 + 对象绑定 + 顺序约束。

2. **TAP（Task Automaton Program，任务自动机）**
   从 `score_steps` + 语言 + 演示编译出每个任务的图：节点是 option 实例，边是 success/failure/undo，守卫是谓词；支持循环（多物体）、顺序（颜色/大小）、计数、并行（双臂）。运行时是一个确定性解释器，不需要 LLM。

3. **RCP + CPA（Runtime Causal Probes + Causal Probe Acceptance，运行时因果探针 + 因果验收）**
   在 WLA 的 residual stream 上训练多标签谓词探针（抓稳/到位/插入/拉上/折叠/被挪走/阶段）；只有通过 CPA 的探针才能当守卫：
   - 反事实准确率（谓词翻转时探针翻转）；
   - 干预敏感性（投影/放大探针方向会改变动作或下游状态）；
   - 跨轴不变性（背景/位置/物体替换下不掉点）；
   - 校准（ECE < 0.1）；
   - 互补性（与几何检查在 OOD 上有差异，否则是冗余）。
   不过 CPA 的探针降级为“日志/辅助”，守卫回退到几何检查 + VLA-FAIL/action consistency。

### 4.3 为什么是现在

- **底座开源**：WLA-1.0-Base 6B + Apache 2.0 + LoRA 代码，让“读内部层 + 微调 action expert”可行[S7]。
- **数据足够**：32k 演示、5 条复述、四路 RGB + EE/夹爪；option 级检索和探针训练不需要额外大数据[S4][S5]。
- **文献就绪**：progress 可读但 steering 无效[S18]、语言探针可能无效[S19]、VLA-FAIL 可检测失败[S17]、Harness/Spark/PALM 证明分层有效[S23][S24][S30]、神经符号任务图是最接近的竞品[S21]。现在缺的是**把这些拼成一个单模型、运行时无 LLM、可审计的系统**。
- **评分结构明确**：成功率第一、步骤分 tie-breaker；终局操作是成功闸门；5 个泛化轴各 2 次[S2][S3]。TRIO 的每个组件都能直接映射到评分。

### 4.4 与上一轮（PILOT-GPR）的关系

| 关系 | 内容 |
|---|---|
| 保留 | WLA 底座；GPR-VLA 主干（目标→残差→动作专家）；TLE/ACP/GF 数据引擎；SSG 的“评分步骤图”思想；OPT 的“相对位姿迁移”；SVL 的“落点/状态校验”；DebugLoop 调试槽；NRB 干扰恢复 |
| 升级 | SSG → **TAP typed automaton**（支持 loop/order/undo/parallel）；OPT → **全 option 参数迁移**（不只放置）；SVL → **RCP + CPA 因果守卫**；NRB → **官方备注忠实 undo 边**；PGL → 并入 `place/insert/hang` 的目标参数 |

### 4.5 与最接近的 6 个工作的工作差异

| 工作 | 它做什么 | 与 TRIO 的关键差异 |
|---|---|---|
| 神经符号 procedural reasoning [S21] | task graph + memory + 外部 perception 验证 | TRIO 用 **VLA 内部因果探针**，不引入外部 VLM/感知模型；且做 option 参数迁移与 CPA |
| Harness VLA [S23] | 冻结 VLA + memory-guided agent + analytic primitives | TRIO 不跑 agent/LLM；状态机离线编译；探针在 policy 内部；有 undo/repair |
| SparkVLA [S24] | stop-aware 分层 + 自适应 chunk | TRIO 是 option 级离散自动机 + 失败归因；不是只学 stop head |
| PALM [S30] | affordance + 连续 progress | TRIO 用离散可验证谓词 + 自动机转移；progress 只是辅助 |
| VLA-Corrector [S27] | latent visual dynamics 检测 + 校正 | TRIO 做语义状态/阶段诊断 + 定向 repair；不只是视觉漂移检测 |
| VLA-FAIL [S17] | action chunk consistency 失败检测 | TRIO 把失败检测接到自动机的 repair/undo；检测只是入口 |

一句话：**TRIO 的新意不在“某个模块”，而在“把可解释性变成可验收的运行时状态，把状态机变成可迁移的 option 组合，把失败检测变成可执行的修复”**。

## 5. 可证伪的押注

### 5.1 三个 hypothesis

- **H1（状态机）**：在长程/多物体任务（T15/T17/T20/T21/T22/T25/T27/T31）上，TAP 相对 flat VLA 提升 full-task 成功率 ≥5pp；消融掉 automaton 后增益消失。
- **H2（因果探针）**：CPA 通过的探针相对“几何守卫”提升人为干扰恢复率 ≥10pp，且 false completion 降低 ≥50%；不过 CPA 的探针没有这个增益（甚至更差）。
- **H3（迁移）**：OPT 相对“固定参数/无检索”在位置/未见物品轴提升 ≥5pp；在背景轴不掉点（因为参数是关系中心的）。

### 5.2 如果失败，怎么退

- 如果 H1 不成立：说明 flat VLA 的隐式状态已经够用，退到“option prompt + 几何守卫 + repair”，不强行上自动机。
- 如果 H2 不成立：说明探针是 epiphenomenal，退到“几何检查 + VLA-FAIL + action consistency”，把可解释性降级为日志/审计，不影响主系统。
- 如果 H3 不成立：说明相对参数迁移在 G1 的观测噪声下不稳，退到“2D 锚点 + 视觉伺服”，不做容器系 6D 迁移。
- 如果真机调试槽显示终局操作提升 <5pp：把火力从“终局”移到“长程状态/干扰恢复”，因为评分结构里步骤分仍是 tie-breaker，且成功率可能被早停/漏步拖累。

### 5.3 一句话押注

**这届比赛最划算的不是再堆一个更大的 VLA，而是把 32 个任务压成 14 个可迁移 option、用因果探针把状态机变成运行时可审计的守卫、用演示检索迁移 option 参数；单模型、零运行时大模型，主攻接触丰富终局操作、长程状态跟踪和人为干扰恢复。**

### 0.5 五条设计原则

1. **评分结构优先**：每个组件都要能映射到“成功率 / 步骤分 / 5 个泛化轴”之一；不能映射的工程复杂度不做。
2. **单模型合规**：运行时只有一个学习模型（WLA checkpoint）；自动机、探针、检索都是确定性代码或同一 checkpoint 的辅助头；不跑第二个 VLM/LLM。
3. **可解释性必须因果**：探针先过 CPA，再当守卫；不过就降级为日志。
4. **迁移的单位是 option + 相对参数**：不复制整段轨迹，不按任务切模型，不做 per-task LoRA。
5. **先能退，再求进**：每个组件都有回退路径；核心系统在没有探针/没有 OPT 时仍能工作。

### 1.7 规则空白与合规判断

| 问题 | 现状 | 本报告的处理 |
|---|---|---|
| 外部数据/仿真数据是否允许 | 公开手册未明确 | 默认只用官方数据；外部数据只做离线对照，不进提交 |

| 人工干预时的安全 | 官方会施加干扰 | 检测到不可恢复/危险状态时停止，不硬撞 |

### 2.2 四种 archetype 与共同缺口

- **Action reasoning**（MolmoAct2）：把“看哪里/怎么动”显式化；但推理结果没有变成可执行的状态机。
- **Multi-embodiment pretraining**（WALL、GR00T、π0.5）：解决“跨本体”，不解决“同一集内被干扰后回退”。
- **World model**（DreamZero、GigaBrain）：解决“预测/数据”，不解决“离散步骤是否完成”。
- **Data-centric / embodied-native**（Spirit、DM0）：解决“真机成功率”，不解决“失败归因”。

共同缺口：**没有显式任务状态、没有 option 级复用、没有因果可验证的运行时状态、没有 undo/repair**。这正是 TRIO 的切入点。

### 4.2 TOL：14 个 option 的 typed 规范

每个 option 是一个 dataclass/JSON：

```python
Option = {
  "name": "insert",
  "prompt": "insert the {object} into the {container}",
  "params": {
    "target_pose": "SE3",        # 容器系/端口系
    "approach_dir": "unit3",     # 接近方向
    "depth": "float",            # 插入深度
    "tolerance": "float",        # 对齐容差
    "force": "float?",           # 可选
    "speed": "float"
  },
  "pre":  ["at_prepose", "object_visible", "gripper_holding"],
  "post": ["inserted"],
  "fail": ["collision", "misaligned", "timeout", "object_dropped"],
  "repair": ["re_align", "regrasp", "withdraw", "push", "re_plan"],
  "timeout_s": 20,
  "max_retries": 2
}
```

关键点：

- **typed**：参数有类型/单位/坐标系；不是自由文本。
- **可组合**：任务自动机只引用 option 名 + 绑定 + 参数。
- **可审计**：每次调用记录 option、参数、谓词、结果。
- **可回退**：`repair` 是有限集合；不会无限重试。

支持的结构：

### 4.4 RCP + CPA：因果探针

#### 4.4.1 探针位置与结构

- 从 WLA 的 VLM/action expert 的残差流取多层特征（例如每 4 层一个池化向量）。
- 每个谓词一个线性/2 层 MLP 头；多标签 sigmoid；时间平滑（GRU/HMM/滑动平均）防抖。
- 谓词集合（可按任务启用）：
  - 抓取：`object_visible`、`at_prepose`、`grasped`、`lifted`、`object_dropped`
  - 运输/放置：`at_target`、`placed`、`stacked`、`stable`
  - 插入/拔出：`aligned`、`inserted`、`extracted`
  - 关节：`open`、`closed`、`zipped`、`unscrewed`、`pressed`
  - 特殊：`hanging`、`folded`、`poured`、`tracked`
  - 阶段：`phase_id`（14 类 + 任务特定子阶段）
  - 异常：`collision`、`human_intervention`、`unreachable`

#### 4.4.2 标签引擎

- **TLE（Temporal Labeling Engine）**：用夹爪开合、EE 速度/高度、动作段、语言步骤、评分步骤，把演示切成 option 段；DTW 对齐同任务不同演示；人工抽检。
- **GF（Geometric Filter）**：用 EE 位姿、夹爪宽度、物体/容器相对位置（离线感知或人工标注子集）生成几何谓词标签。
- **ACP（Adversarial Counterfactual Pairs）**：对同一帧做位置/背景/物体/干扰编辑，生成正负对；用于训练不变性与 CPA。
- **NRB（Narrative Repair Bank）**：把官方 `generalization.human_1_note` / `human_4_note` 转成“破坏→恢复”片段；用于训练 repair/undo 分类器与探针的回归检测。
- **HITL（Human-in-the-loop）**：对高价值谓词（inserted/zipped/unscrewed）抽 500–1000 帧人工标注，做校准集。

#### 4.4.3 训练损失

```text
L = Σ BCE(pred_i, y_i)
  + λ_c * Contrastive(z_pos, z_neg)
  + λ_i * Invariance(z, augment)
  + λ_t * TemporalSmooth(pred_t, pred_{t-1})
  + λ_k * Calibration(pred, y)
```

- `Contrastive`：同谓词正样本 vs 反事实负样本。
- `Invariance`：背景/位置/光照/干扰物增强后，谓词预测不变。
- `TemporalSmooth`：鼓励阶段内稳定、边界处跳变。
- `Calibration`：温度缩放/ECE 正则。

#### 4.4.4 CPA 五项

| 项 | 问题 | 通过标准（建议） |
|---|---|---|
| 反事实准确率 | 谓词翻转时探针是否翻转？ |  held-out 反事实对 >95% |
| 干预敏感性 | 投影/放大探针方向是否改变动作或下游状态？ | 干预组 vs 对照组动作差异 >δ；小规模真机/仿真验证 |
| 跨轴不变性 | 背景/位置/未见物体下是否掉点？ | AUC 下降 <5pp |
| 校准 | 置信度是否可信？ | ECE <0.1 |
| 互补性 | 与几何检查是否有 OOD 差异？ | 在 OOD 子集上 disagreement >5%，否则视为冗余 |

> **关键**：CPA 不是“论文里的可解释性指标”，而是**上线门禁**。不过的探针只写日志，不参与转移。

#### 4.4.5 探针伪代码

```python
def train_probe(features, labels, cf_pairs, aug_pairs):
    probe = MLP(in_dim=features.dim, out_dim=n_pred)
    for batch in loader:
        z, y = batch
        pred = probe(z)
        loss = bce(pred, y)
        loss += λ_c * contrastive(probe(z_pos), probe(z_neg))
        loss += λ_i * invariance(probe(z), probe(aug(z)))
        loss += λ_t * smooth(pred)
    return calibrate(probe)

def cpa(probe, cf_set, aug_set, intervention_set):
    return {
      "cf_acc": accuracy(probe, cf_set),
      "intervention_delta": intervention_effect(probe, intervention_set),
      "axis_drop": max_auc_drop(probe, aug_set),
      "ece": expected_calibration_error(probe),
      "complementarity": disagreement(probe, geometric_checks)
    }
```

### 4.5 OPT：option 参数迁移

#### 4.5.1 迁移什么

对每个 option 实例，迁移的是**相对参数**，不是绝对轨迹：

- `place`：容器系释放位姿 `T_container_release`；支撑面高度；叠放偏移。
- `insert`：端口系插入方向 `d`、深度 `h`、容差 `ε`。
- `extract`：抓取点 + 拔出方向 + 行程。
- `articulate`：把手抓取位姿 + 旋转轴/方向 + 行程。
- `hang`：钩系释放位姿 + 释放时机。
- `fold`：折线 + 抓取点 + 折叠方向。
- `pour`：倾斜角 + 推程/流量 + 停止条件。

#### 4.5.2 检索键

- 关系中心：物体/容器相对位姿、夹爪开度、阶段、运动方向。
- 语言：option prompt + 任务复述。
- 视觉：物体/容器局部特征（DINO/CLIP 或 WLA 内部特征），**不用全局背景**。
- 失败历史：上次失败类型/修复动作（避免重复同一错误）。

#### 4.5.3 稳健统计与控制模式

```text
T* = median_k(T_i)                 # 相对位姿
u  = MAD_k(T_i) / scale            # 离散度
mode = direct   if u < τ1
     = servo    if τ1 ≤ u < τ2
     = conservative otherwise
```

- `direct`：直接执行，速度快。
- `servo`：视觉伺服到目标，边走边校正。
- `conservative`：小步、低增益、多次校验；用于透明/可变形/接触丰富。

#### 4.5.4 与 PGL 的关系

上一轮 PGL 是“槽位/区域 → 2D 锚点 → 6D 位姿”的放置目标阶梯。本轮把它并入 `place`/`insert`/`hang` 的参数生成：

- 粗目标：语言/评分步骤给出槽位/区域；
- 中目标：视觉锚点/目标头给出 2D/3D 点；
- 精目标：OPT 给出容器系 6D 相对位姿；
- 收尾：SVL/repair 做最后校验。

### 4.6 Repair / Undo / Memory

#### 4.6.1 诊断表

| 观察 | 诊断 | 修复 |
|---|---|---|
| `grasped` 变 false / 物体不随动 | 抓取失败/滑脱 | `regrasp`，换抓取点/宽度 |
| `at_target` false + 碰撞/接近失败 | 路径/对齐错误 | `re_align` / `withdraw` / 换接近方向 |
| `inserted` false + 深度不足 | 插入未到位 | `push` / 小幅往复 / 加大力（若允许） |
| `placed` false + 物体在目标附近 | 释放位姿偏 | `nudge` / `re_place` |
| `zipped`/`open` 回归 | 人为干扰/回弹 | `undo` 到上一节点，重做 `articulate` |
| 对象消失/不可达 | 不可恢复干扰 | `abort`，保留部分分，避免撞 |
| 连续两次同失败 | 策略/参数错 | `re_plan`，换 option 参数或换 option |

#### 4.6.2 修复算子

- `regrasp`：重新 `reach` + `grasp`，可换抓取点/角度。
- `re_align`：退到预插入位姿，重估端口/容器位姿。
- `withdraw`：沿插入/接近反方向退出，解除卡滞。
- `push`：小幅直线推入（插入/按压）。
- `nudge`：小幅横向/纵向微调（放置）。
- `re_place`：重新抓起并放置。
- `undo`：沿自动机 undo 边回退一个节点。
- `re_plan`：换 option 或换参数，限一次。
- `abort`：停止，保留部分分。

#### 4.6.3 时间预算

- 每 option 超时：5–25s（按任务）。
- 每 option 重试：≤2；全局 `re_plan`：≤1。
- 预留 20% 时间给 repair；超过 80% 预算后只完成当前节点，不再开新重试。
- 180s 上限是硬约束；平均演示时长 ~6s（HangCup 中位 177 帧），预算充足，但长程任务（T31/T17/T15）要限重试。

#### 4.6.4 Memory

- 已完成节点集合、对象绑定、上次谓词向量、上次修复动作、重试计数、人为干扰标志。
- 记忆是**结构化状态**，不是长上下文；避免 VLA 上下文爆炸。
- 可选：把记忆压缩成 state token（见 4.7）。

### 4.7 State token：让状态“行为相关”

`Not All Features` 的教训是：语言/状态探针可能只存在于表征里，行为不看它 [S19]。所以不能只读状态，还要**把状态注入 policy**：

```text
state_token = MLP([option_emb; predicate_vec; memory_vec; param_vec])
```

- 注入位置：action expert 的 cross-attention 条件（与语言 token 并列），或作为前缀 token。
- 训练：LoRA action expert；输入 = 观测 + 语言 + state token；输出 = action chunk。
- 监督：flow-matching action loss + 辅助谓词/阶段 loss。
- 推理：state token 由自动机 + 探针确定性计算；不依赖 LLM。
- 回退：如果 state token 训练不稳定，先用 prompt 拼接（option + 状态摘要），再逐步过渡。

这解决了两个问题：

1. **语言被视觉淹没**：状态 token 是显式的、非语言的通道，不靠 VLM “听懂”。
2. **探针 epiphenomenal**：状态 token 迫使 action expert 使用状态信息；CPA 的干预敏感性也有更强的测试基础。

### 4.8 运行时伪代码

```python
class TrioRuntime:
    def reset(self, task_id, language):
        self.program = load_program(task_id)
        self.state = init_state(self.program, language)
        self.memory = []
        self.t0 = now()

    def step(self, obs):
        # 1. 读状态
        p = self.probes(obs)                  # 多标签谓词 + 阶段
        p = self.smooth(p)
        self.state = update(self.state, p)

        # 2. 完成/失败/超时
        if self.program.success(self.state, p):
            return self.finish(success=True)
        if now() - self.t0 > self.program.budget_s:
            return self.finish(success=False, reason="timeout")

        # 3. 转移/修复
        decision = self.transition(self.state, p)
        if decision.kind == "advance":
            self.state.node = decision.next
        elif decision.kind == "undo":
            self.state.node = decision.prev
        elif decision.kind == "repair":
            return self.repair(decision.repair, obs, p)
        elif decision.kind == "abort":
            return self.finish(success=False, reason=decision.reason)

        # 4. 参数 + state token + 动作
        opt = self.program.node(self.state.node)
        params = self.opt.retrieve(opt, obs, p, self.memory)
        token = self.state_token(opt, p, self.memory, params)
        action = self.vla.act(obs, opt.prompt, params, token)
        self.log(opt, p, params, action)
        return action
```

### 4.9 延迟与合规

- 探针：小 MLP，<5ms（GPU/CPU）。
- 自动机/检索：<10ms（预编译/缓存）。
- VLA 前向：主导；按 WLA 实际测量。
- 额外开销目标 <5%；180s 预算下可接受。
- 单模型：一个 WLA checkpoint + 同一权重包内的辅助头；自动机/检索是代码/数据，不是第二个模型。
- 多机器人并发：episode 级状态隔离；检索缓存只读；日志按 episode ID。

- 人为干扰：human_4 “拉上之后拉开” → `zipped` 回归 → `undo` 到 `articulate(zipper, zip)`，重做。

#### T27 Stack Bowls

#### T31 Organize Pencil Case

- 守卫：`zipper_open`、`all_items_in`、`zipped`。
- 人为干扰：备注为空；但长程/多物体，重点在计数与顺序。

## 6. 因果探针与 CPA（细节）

### 6.1 为什么用 VLA 内部探针，而不是外部视觉分类器

- 外部分类器是第二个模型，增加合规/延迟/域差风险。
- VLA 内部表征已经包含“任务相关”的状态；探针读的是 policy 自己的状态，不是旁观者的状态。
- 但内部探针可能是 epiphenomenal；CPA 用来筛掉。
- 回退：几何检查 + VLA-FAIL 的 LLMD/ACC（不需要失败数据）[S17]。

### 6.2 探针的层级选择

- 不固定某一层；对每层/每 4 层训练线性探针，选 CPA 最好的层。
- 多标签共享 trunk，减少参数；每个谓词一个头。
- 时间模型：轻量 GRU 或 HMM；窗口 5–15 帧（30fps 下 0.17–0.5s）。
- 输出：概率 + 置信区间（可选）；低于阈值时回退几何检查。

### 6.3 标签的噪声与人工校验

- TLE 的 phase 标签是弱标签；用 DTW + 人工抽检 5%。
- GF 的几何标签在遮挡/透明物体上不可靠；用人工标注子集校准。
- ACP 的反事实对是构造标签，质量高；但可能与真实 OOD 有域差。
- NRB 的干扰片段来自官方备注，质量高；但覆盖有限。
- **建议**：先做 3 个谓词（`grasped`、`inserted`、`zipped`）的闭环，验证 CPA 流程，再扩展。

### 6.4 CPA 的干预敏感性怎么测

- **离线**：投影掉探针方向，测 action chunk 的变化（L2/方向/夹爪）；如果几乎不变，探针是 epiphenomenal。
- **仿真/回放**：在关键帧注入探针方向，测下游谓词/成功率；需要可交互环境。
- **真机**：调试槽里对小范围关键帧做干预，测动作/成功率；成本高，只做少量。
- **替代**：用 action chunk consistency + 反事实动作差异作为代理；不完美，但比只看 probe accuracy 强。

### 6.5 CPA 通过后的使用方式

- **守卫**：`if p[post] > θ_hi and p[stable] > θ_s: advance`。
- **诊断**：`if p[grasped] < θ_lo: regrasp`。
- **日志**：所有谓词值 + 置信度 + 证据（几何/视觉）。
- **降级**：探针连续 N 帧低置信/与几何冲突 → 切换到几何守卫，并记录。

### 6.6 探针失败的回退

| 失败 | 回退 |
|---|---|
| CPA 反事实准确率低 | 不用该探针；用几何/视觉检查 |
| 干预敏感性低 | 只做日志，不做守卫 |
| 跨轴掉点 | 按轴禁用；或改用轴不变特征 |
| 校准差 | 温度缩放；仍差则禁用 |
| 互补性低 | 与几何检查合并，减少冗余 |

## 7. Option 参数迁移（细节）

### 7.1 相对参数的定义

以 `place` 为例：

```text
T_release_i = T_container^{-1} @ T_ee_release_i
```

- `T_container`：容器/目标坐标系（由目标头/几何/视觉估计）。
- `T_ee_release_i`：第 i 条演示中释放时的 EE 位姿。
- 对 K 条相似演示取中位数 `T*`，离散度用平移/旋转 MAD。

以 `insert` 为例：

```text
d_i = normalize(T_port^{-1} @ T_ee_approach_i)   # 接近方向
h_i = projection(T_port^{-1} @ T_ee_insert_i)     # 插入深度
```

### 7.2 检索键的构造

```text
key = [rel_obj_pose, rel_container_pose, phase, gripper_width,
       language_embedding, local_visual_feature, last_failure_type]
```

- 归一化后加权；关系项权重最高。
- 检索池按任务/option 分桶；跨任务共享只在同 option 内。
- 缓存演示特征；推理时只做最近邻，延迟可控。

### 7.3 控制模式选择

```text
u = w_t * trans_mad / scale_t + w_r * rot_mad / scale_r
if u < τ1: direct
elif u < τ2: servo
else: conservative
```

- `direct`：直接执行相对位姿。
- `servo`：用视觉/目标点闭环到目标。
- `conservative`：小步、低增益、频繁校验；用于透明/可变形/高接触。

### 7.4 与语言/目标头的关系

- 语言给出“做什么/放到哪”的语义；OPT 给出“具体怎么放”的几何。
- 如果 WLA 有目标点/空间 grounding 头（若底座支持），用它的输出作为 `T_container` 的粗估；否则用立体视觉/几何。
- 目标头是同一 checkpoint 的辅助头；不是第二个模型。

### 7.5 失败时的参数更新

- 第一次失败：在 `T*` 附近采样小扰动（±容差），选最接近几何检查的。
- 第二次失败：换控制模式（direct → servo → conservative）。
- 第三次失败：`re_plan`，换 option（例如 `place` → `insert` 或 `press`）。

## 8. 失败诊断与修复（细节）

### 8.1 诊断信号

| 信号 | 来源 | 用途 |
|---|---|---|
| 谓词概率 | RCP | 状态转移/回归 |
| 几何检查 | EE/夹爪/目标点 | 抓取/对齐/深度 |
| 动作一致性 | VLA-FAIL ACC [S17] | 异常检测 |
| 视觉动态 | VLA-Corrector LVM [S27] | chunk 内漂移 |
| 对象消失 | 视觉/目标头 | 不可恢复干扰 |
| 时间/重试 | 自动机 | 预算控制 |

### 8.2 修复算子表

| 算子 | 适用 | 动作 | 风险 |
|---|---|---|---|
| `regrasp` | 抓取失败/滑脱 | 退到预抓取，换点/宽度 | 二次碰撞 |
| `re_align` | 插入/放置对齐失败 | 退到预位姿，重估目标 | 时间 |
| `withdraw` | 卡滞/插入过深 | 沿反方向退出 | 拉飞物体 |
| `push` | 插入深度不足/按压 | 小幅直线推 | 过力 |
| `nudge` | 放置偏一点 | 小幅横向/纵向推 | 推倒 |
| `re_place` | 释放位姿错 | 重抓重放 | 时间 |
| `undo` | 人为干扰/步骤回归 | 回退一个节点 | 重复劳动 |
| `re_plan` | 连续同失败 | 换 option/参数 | 不稳定 |
| `abort` | 对象消失/不可达 | 停止 | 放弃部分分 |

### 8.3 人为干扰的 undo 边

官方 `generalization` 备注已经给出剧本 [S3]：

- T19：拉上拉链之后拉开 → `zipped` 回归 → undo 到 zip。
- T27：叠了第二个之后拿下第二个 → `bowl2_stacked` 回归 → undo 到 place(bowl2)。
- T14：拧开盖子之后拧动回来 → `unscrewed` 回归 → undo 到 articulate(cap)。
- T17：笔盒合上之后手动打开 → `closed` 回归 → undo 到 close。
- T10：将插头拔起 → `inserted` 回归 → undo 到 insert。
- T01：杯子向后/向右 → `hanging` 回归 → re_align/re_hang。

这些不是“额外数据”，是**官方给的恢复剧本**；NRB 把它们变成训练/评测片段。

### 8.4 不可恢复情形

- 对象被抽走（T12 human_4）→ `object_visible` false；如果目标不可达，`abort`。
- 目标容器被移出工作空间（T26 human_4 把插口移开）→ 重估；如果不可达，`abort`。
- 人为干扰导致安全风险（碰撞/夹手）→ 立即停止。
- 不要为了“看起来在努力”而无限重试；保留部分分更划算。

### 8.5 部分分策略

- 评分是步骤分；即使最终失败，完成的前置步骤仍有分。
- 自动机的 `success` 是最终目标；但 `progress` 按步骤权重累计。
- 当时间不足/不可恢复时，优先完成当前步骤，而不是开新步骤。
- 记录部分分估计，用于离线分析（不要用于运行时自欺）。

## 9. 训练配方

### 9.1 四个阶段

| 阶段 | 目标 | 数据 | 训练 | 产出 |
|---|---|---|---|---|
| S0 基线 | 复现 WLA 32 任务 | 官方 32k | LoRA action expert + 任务 prompt | 基线 checkpoint |
| S1 option 条件 | 让 VLA 听懂 option prompt | 官方 + TLE 段标签 | LoRA + option prompt | option 条件 checkpoint |
| S2 state token | 让状态行为相关 | S1 + 谓词/阶段标签 | LoRA + state token + 辅助头 | TRIO checkpoint |
| S3 恢复 | 干扰/修复鲁棒 | S2 + NRB/ACP | 硬负样本/恢复片段 | 最终 checkpoint |

### 9.2 数据引擎

- **TLE**：阶段分割 + DTW 对齐 + 人工抽检。
- **ACP**：位置/背景/物体/干扰编辑；生成正负对。
- **GF**：几何谓词标签；遮挡/透明处降权。
- **NRB**：官方 human 备注 → 破坏/恢复片段。
- **HITL**：500–1000 帧高价值谓词人工标注；只做校准/测试，不训练到过拟合。

### 9.3 损失

```text
L_total = L_action (flow matching / regression)
        + λ_phase * L_phase (CE)
        + λ_pred * L_pred (BCE)
        + λ_cons * L_consistency (action chunk)
        + λ_inv * L_invariance (ACP)
```

- `L_action`：WLA 原生动作损失（按官方训练代码）。
- `L_phase`/`L_pred`：辅助头，只在有标签的段计算。
- `L_consistency`：同一状态不同增强下动作一致（可选）。
- `L_invariance`：背景/位置增强下谓词/动作不变（可选）。

### 9.4 LoRA 与超参

- 冻结 VLM，LoRA action expert（WLA 官方支持）[S7]。
- rank/alpha/lr 按官方脚本；先跑小规模 sweep。
- 混合精度；梯度检查点；按显存调 batch。
- 先训 S0/S1，确认不破坏基线；再加 S2/S3。
- 探针单独训练（冻结 VLA），不参与主损失。

### 9.5 计算与工程

- 6B + LoRA：单机多卡可训；推理单卡（具体显存按量化/精度实测）。
- 探针/自动机：CPU 即可；检索缓存放内存/SSD。
- 日志：每 episode 保存状态轨迹、谓词、动作、修复；便于失败分析。
- 版本：task program、probe、checkpoint、阈值都打版本号；可回滚。

## 10. 实验设计

### 10.1 Hypotheses

- **H1（状态机）**：TAP 在长程/多物体任务上相对 flat VLA +5pp full-task success；消融 automaton 后增益消失。
- **H2（因果探针）**：CPA 探针相对几何守卫，人为干扰恢复率 +10pp，false completion −50%；非 CPA 探针无增益。
- **H3（迁移）**：OPT 在位置/未见物品轴 +5pp；背景轴不掉点。
- **H4（state token）**：state token 相对 prompt-only 提升步骤遵循/长程完成率；消融后回退。
- **H5（可选 WM）**：TRIO-WM 只在模糊关键帧提升，若延迟超预算则关闭。

### 10.2 Baselines

1. WLA-1.0-Base + 32 任务 LoRA（官方基线）。
2. Flat VLA + task prompt（无自动机）。
3. Flat VLA + step prompt（无探针/自动机）。
4. Automaton + 几何守卫（无探针）。
5. Automaton + 相关性探针（无 CPA）。
6. Full TRIO（CPA + OPT + state token + repair）。
7. 可选：Harness 风格 planner + frozen VLA；SparkVLA 风格 stop-aware（若可复现）。

### 10.3 Metrics

- **主**：32 任务平均成功率；接触丰富子集成功率。
- **次**：平均步骤分；平均时长；超时率。
- **恢复**：人为干扰后恢复率；undo 成功率；false completion。
- **状态**：phase F1；谓词 AUC/F1；CPA 通过率；校准 ECE。
- **效率**：自动机/探针延迟；API p50/p99；单任务总时长。
- **安全**：碰撞/超力/急停次数（若可观测）。

### 10.4 离线实验

- **阶段分割**：held-out 演示的 phase F1 >0.9；边界误差 <0.5s。
- **谓词探针**：AUC >0.9（grasped/inserted/zipped）；ECE <0.1。
- **CPA**：反事实 >95%；跨轴掉点 <5pp；干预敏感性显著。
- **自动机回放**：给定演示状态，next-option accuracy >90%；undo 触发正确率 >80%。
- **跨任务 split**：24 任务训练 / 8 任务测试，测 option 库迁移；目标 >基线 +3pp（仅研究，不影响提交）。

### 10.5 真机/调试槽

- 单任务调试槽（不计分）：优先 T26（插入）、T12（关节）、T19（拉链）、T27（叠放）、T31（长程）。
- 每个任务 5–10 次，做 A/B：基线 vs TRIO；记录成功/失败类型/时长。
- 调试槽是“发布门”，不是“调参器”；每个大版本最多 1–2 槽。
- 正式计分跑：32 任务 ×10；至少 2 次（初版/修复版），观察方差。

### 10.6 统计功效

- 32 任务 ×10 = 320 trials；p≈0.3 时二项 SE ≈ 2.56pp。
- +5pp 约 1.95 SE（单侧 p≈0.026）；但任务间异质性大，需按任务配对 bootstrap。
- 10 次/任务的方差可能很大；不要用单任务 1–2 次的结果做结论。
- 调试槽样本小，只看方向性/失败类型，不做显著性宣称。

### 10.7 Go/No-Go gates

| Gate | 条件 | 决策 |
|---|---|---|
| G1 | S0 基线复现，32 任务可跑通 | 继续 |
| G2 | 离线 phase/谓词达标；CPA 流程跑通 | 继续 |
| G3 | 调试槽 T26/T12 的 full-task +5pp | 继续；否则回退轻量版 |
| G4 | 调试槽 T19/T27 不退化 | 继续；否则砍 OPT/WM |
| G5 | 正式跑 +5pp 且无安全事件 | 提交/冻结 |

## 11. 创新点清单

### 11.1 押注（必须做）

- **I1 TAP typed option automaton**：把公开评分步骤编译成可执行、可审计、支持 loop/order/undo/parallel 的任务图；不是手写 FSM，也不是运行时 LLM。
- **I2 CPA 因果探针**：把“可解释性”变成上线门禁；反事实/干预/不变性/校准/互补性五道关；不过就降级。
- **I3 OPT option 参数迁移**：跨任务/跨演示迁移相对位姿/方向/深度；不是复制轨迹，不是 per-task 微调。

### 11.2 保留/升级（差异化）

- **I4 state token 注入**：把 option/谓词/记忆/参数注入 action expert，解决“语言被视觉淹没/探针 epiphenomenal”。
- **I5 失败归因 + repair/undo**：检测不是终点；诊断到具体失败类型，选对修复/回退。
- **I6 NRB 官方备注忠实化**：把 human_1/human_4 备注变成 undo/恢复片段，而不是自造干扰。
- **I7 TLE/ACP/GF 数据引擎**：弱标签 + 反事实 + 几何，低成本训练探针。
- **I8 SVL/几何守卫**：探针失败时的安全网；保证系统可退。
- **I9 DebugLoop**：不计分单任务调试槽做发布门，而不是盲调。

### 11.3 观察/可选（高不确定）

- **I10 TRIO-WM**：轻量世界模型验证 option 结果；只在延迟允许时用。
- **I11 跨模型蒸馏**：把 MolmoAct2/WALL/DreamZero/Spirit 的互补强项蒸馏进一个学生；规则/算力允许才做。
- **I12 LAC 跨本体适配**：用 latent action 迁移外部预训练；官方数据已够，优先级低。

### 11.4 降级/砍（不做）

- 全 32 任务高保真数字孪生。
- 运行时仿真/MPC/RL。
- 每任务 LoRA / 多模型路由 / 运行时 LLM planner。
- 外部数据农场作为研究主轴。
- “终局放置”单点押注（扩展到接触丰富终局 + 状态跟踪 + OOD）。
- 依赖占位榜单的排名/难度推断。

### 11.5 如果只能做三件事

1. **TAP + 几何守卫 + repair**（无探针也能跑，先拿状态机/恢复的收益）。
2. **加 OPT**（位置/未见物品轴的迁移）。
3. **加 CPA 探针 + state token**（可解释性/干扰恢复的差异化）。

## 12. 风险与合规

### 12.1 技术风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 探针 epiphenomenal | 高 | 中 | CPA；不过就降级；几何/VLA-FAIL 兜底 |
| 阶段标签噪声 | 中 | 中 | 多信号 + DTW + 人工抽检；守卫比标签重要 |
| state token 破坏基线 | 中 | 高 | 先 prompt；LoRA 小步；A/B；可回退 |
| OPT 在透明/可变形上失效 | 高 | 中 | 分桶；只做相位/2D 锚点；conservative 模式 |
| 自动机覆盖不全 | 中 | 中 | 32 任务手工审阅；未知段回退 flat VLA |
| 人为干扰不可恢复 | 中 | 低 | abort；保留部分分；安全优先 |
| 延迟超预算 | 低 | 中 | 探针/检索 <10ms；缓存；chunk 级 |
| 过拟合调试槽 | 中 | 高 | 调试槽只做发布门；正式跑多任务 |

### 12.2 规则风险

- **单模型**：一个 checkpoint + 同一权重包的辅助头；不跑第二个 VLM/LLM/感知模型。
- **外部数据/权重**：默认不用；如用，先书面确认；离线研究不提交。
- **远程 API**：服务内部状态隔离；不依赖平台提供额外计算；p99 延迟达标。
- **安全**：人为干扰下优先停止；不硬撞；日志可审计。
- **模型卡**：写明底座、数据、LoRA、探针、阈值、合规声明、已知限制。

### 12.3 工程风险

- 多机器人并发：episode 状态隔离；检索缓存只读；日志按 ID。
- 版本漂移：task program/probe/threshold 版本化；正式跑前冻结。
- 数据管线：LeRobot v3 格式；视频解码/帧对齐；30fps 时间戳。
- 复现：固定 seed；记录环境/依赖/硬件；保存失败案例。

### 12.4 伦理/安全

- 不采集/不使用未授权数据；不用比赛数据做与比赛无关的用途。
- 真机调试遵守平台安全规则；不绕过急停/限位。
- 失败日志不包含敏感信息；模型卡公开合规声明。

## 15. 开放问题

1. **WLA 的实际动作空间/频率/延迟**：joint 还是 ee？action chunk 多长？p99 多少？需要在 S0 实测。
2. **WLA 的中间层是否适合探针**：哪一层线性可分最好？action expert 的 cross-attention 是否可注入 state token？需要代码级确认。
3. **官方评分脚本的“步骤完成”判定**：是人工/视觉/状态？`score_steps` 是文字，实际判定可能更严；需要调试槽观察。
4. **人为干扰的触发时机/幅度**：备注给了剧本，但具体时机/幅度未知；NRB 只能近似。
5. **单模型合规的边界**：探针/辅助头是否算同一模型？建议导出为同一权重包，并在模型卡声明。
6. **外部数据/预训练权重**：手册未明确；默认不用；如要用，先书面确认。
7. **透明/可变形/反光物体的感知**：T13/T19/T23/T32 是高风险；OPT/探针可能失效，需分桶回退。
8. **多机器人差异**：官方多台 G1，相机/夹爪/桌面可能有差异；需要域随机化/在线校准。
9. **正式跑的次数/成本**：未知；按 2 次正式跑 + 2 次调试槽做预算。
10. **排行榜真实水平**：占位数据不可信；如果真实榜首远高于 30%，+5pp 的目标仍然有意义，但策略可能需要更激进。

## 16. 结论

TRIO-GPR 的核心不是“再加一个模块”，而是把三件事绑在一起：

- **迁移学习**：14 个共享 option + 相对参数 + 不变谓词，让 32 个任务互相放大；
- **可解释性**：CPA 因果探针 + 审计轨迹，让状态在运行时可信、可用；
- **状态机**：TAP typed automaton + undo/repair，让长程、多物体、人为干扰可跟踪、可恢复。

它全部跑在一个 6B WLA checkpoint + 确定性代码里，符合单模型约束；每个组件都有回退路径；每个 hypothesis 都可证伪。**如果只能押一个方向：把评分步骤变成自动机，把自动机的守卫变成因果探针，把 option 参数从演示里迁移过来。**
