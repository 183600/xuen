# 第 8 轮 · DCSG：决策关键相位上的群体几何总督（当前灵感循环第 2 轮）

> 检索/复核日期：**2026-10-25（UTC）**。赛事身份不变：宇树科技 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署、官方远程真机 API 评测。本轮三个灵感词是「群体智能」「Gazebo」「低成本方案」。我先各自钉到可核实的事实上，再给出主判断：**VLA 的语义能力已经够用，真正的边际在“最后三厘米”的几何决策；用一个只在决策关键相位启动的 CPU 粒子群总督（DCSG），把官方演示当种子、把确定性几何当适应度、把共识/边际当门控、把 Gazebo 当负样本校准器，可以在不重训、不加第二个学习模型、单卡 24GB 的约束下，同时改善抓取、插入、放置三类跨轴执行相位。** 这是对第 7 轮 PILOT-GPR 的聚焦修正：保留它的 SSG/OPT/PGL/ICR/SVL/NRB 基础设施，但把“终局放置是唯一闸门、步骤分是主目标”改为“成功率优先、三类决策关键相位、群体几何搜索”。

## 0. 本轮先核实：七个事实

### 0.1 规则把目标函数钉死：成功率 > 步骤分 > 提交日期

官方参赛手册（[S1]）写明：

| 项目 | 官方原文/可核实内容 | 对方案的含义 |
|---|---|---|
| 赛道 | 通才模型赛道；一个模型完成全部 32 任务；**不得混合多个模型** | 不能做多模型 ensemble；DCSG 必须是确定性代码，不能是第二个学习模型 |
| 试次 | 每任务 10 次独立运行；5 类泛化（位置/干扰物/背景/未见物品/人为干扰）**各 2 次** | 共 **32×10=320** 次；单轴只占 2/10=20% |
| 时限 | 单次真机执行 **≤180s**，超时记失败，按执行情况给步骤分 | 短任务可重试；长任务要预算 |
| 排名 | **32 任务总平均成功率**降序；相同则总平均步骤分降序；仍相同则**提交日期早**者靠前 | 成功率是第一目标；步骤分只是 tie-break；早提交有价值 |
| 部署 | 选手自部署；平台远程 API 调用；N 台机器人，端口 **8765 起连续 N 个** | 服务稳定性、并发、时延是比赛的一部分 |
| 调试 | 不计分单任务测试通道 | 真机反馈稀缺，必须做配对实验/机制指标 |
| 观测/动作 | 4 路 RGB、双臂关节/EE 位姿、夹爪、language；动作是位置目标（joint 或 EE 二选一）+ 夹爪开度 + pivot | **API 不暴露力/刚度命令**；柔顺只能靠行为（慢、停、部分闭合、回退、搜索） |

这条规则直接推翻了一个常见误读：第 7 轮把“步骤分约占 60%”当成主目标，但排名先比成功率——**为了多拿一步部分分而牺牲一次完整成功，是负期望**。步骤分只在成功率打平时值钱，早提交也只在两者都打平时值钱。

### 0.2 数据规模与结构：33,276 条、811.3GB、169.28 小时

我用 HF API 对 collection 的 32 个数据集逐个汇总（[S5]）：

- **32 个任务，合计 33,276 episodes / 18,282,246 frames / 169.28h（30fps）/ 811.3GB**。
- 单任务 969–1,533 条；StackBowls 979 条 / 295,609 帧 / 30fps（[S6]）；PlugCharger 1,022 条 / 463,451 帧（[S7]）。
- 四路相机：`head_stereo_left/right`（已校正）+ `wrist_left/right`，480×640×3，AV1，30fps；**没有深度流**，但头部是立体对，可本地做经典立体匹配。
- 状态/动作：双臂 7+7 关节、夹爪 1+1、下肢 15、EE 位姿在 **base 与 torso 两套坐标**（各 6 维）、torso/D435 位姿、`action.pivot`、`base_command` 等；Dex1 夹爪范围 5.5–0.0（open→close）。
- 每条任务 5 条英文复述（`@` 分隔）。本轮再次实测 StackBowls：`Stack the three bowls in the order: red, green, blue.@Pile three bowls following red, green, blue sequence.@Layer three bowls in red then green then blue order.@Make a stack of three bowls ordered red, green, blue.@Set three bowls stacked as red, green, blue.`（[S8]）。第 7 轮已实测 HangCup/ZipUp/PlugCharger 也是 5 条。
- 演示时长差异很大：HangCup 平均约 6.2s，ToolboxStorage 平均约 37.6s；32 任务总平均约 18.3s。180s 对短任务是“可重试”，对长任务是“少犯错”。

**对 DCSG 的含义**：33k 演示里最值钱的不是画面，而是**带 EE 位姿的成功轨迹**——它们给出每个任务在每个相位的“几何先验”：抓取点、插入方向、释放位姿。DCSG 不需要重新训练一个位姿预测器，只需要把这些位姿统计成种子和适应度先验。

### 0.3 接口与部署：N 端口、共享后端、状态隔离、时延记录

提交模板 README（[S9]）给出：

- 评测在 **N 台机器人**上随机顺序进行；N 由官方另行公布；必须暴露 **N 个连续端口**（8765, 8766, …, 8765+N−1），端口数必须与 N 完全一致。
- **允许多端口共享一份模型**，但必须自己实现请求分发；共享后端要并发处理，避免互相阻塞；**每个端口的 `reset` 与历史状态必须严格隔离**。
- 每次 `get_action` 的**时延和内容都会被记录**；官方会结合每步时延、波动、动作统计规律评估结果可信度。
- `metadata` 决定：`control_space`（joint/ee 互斥）、`obs_delta_indices`（传哪些键 + 每键叠几帧）、`image_resize`、`action_chunk_size`、`token`。
- 动作是位置目标：EE 动作是 base 系绝对 `xyz+rpy`；夹爪是开度；`action.pivot` 是下肢/转台。**没有力/力矩/刚度命令**。

**对 DCSG 的含义**：DCSG 完全可以落在接口内——它只在 EE 动作空间里覆盖“最后三厘米”的位置目标；观测裁剪/缩放/叠帧由我们控制；N 端口共享后端是官方允许的省卡方式。

### 0.4 WLA-1.0-Base：6B、Apache 2.0、单卡 24GB、原生 EE

官方仓库与配置（[S10][S11]）：

- **6B 参数**，2026-09-28 发布 Base 与微调代码，Apache 2.0。
- 架构：Qwen-VL 主干 + MMDiT action expert；`action_dim=54`、`action_horizon=30`、`num_inference_timesteps=4`。

**对 DCSG 的含义**：底座不需要换；DCSG 是底座之上的确定性几何层。4 步去噪 + 30 步 horizon 给出足够快的 chunk；DCSG 只需要在 chunk 的末端附近改写几个 EE 目标。

### 0.5 榜单仍是占位：不能把 29.7% 当“榜首”

- `leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`；8 个模型 × 32 任务 = 256 条 `task_metrics`（[S3]）。
- 8 个占位模型的平均成功率 20.5–29.7%，平均步骤分 28.1–39.0%；MolmoAct2 的 29.7% 只是脚本生成值。
- `runs.html` 仍是 256/256 占位，详情页写明“测试视频占位”（[S4]）。
- **唯一可谨慎使用的量**：占位数据里“步骤分−成功率”的逐任务差值从 **6.0pp（Plug In Ethernet）到 10.3pp（Stack Cups）** 不等。高差值意味着“失败发生在后段步骤”的比例更高（叠杯、传送带、耳机盒、纸杯、相框、果篮）；低差值意味着“更早失败”（插网线、开锁、拼字母、文具收纳、开药瓶、挂杯）。这只能当**弱先验**，不能当因果或真实排名。

### 0.6 Gazebo 资产：G1 + Dex1 的 URDF 现成，但只适合窄用

- `unitree_ros` 提供 G1 的 URDF/launch/world/plugin；`robots/g1_description` 里明确有 **`g1_29dof_mode_15_with_dex1_1.urdf`**（G1 29DoF + Dex1 手）（[S12][S13]）。
- README 同时写明：Gazebo 可做关节级低层控制（位置/速度/力矩），**不能做高层行走**；依赖标注为 ROS Melodic + Gazebo8（[S12]）。
- 桌面任务基座固定，**“不能行走”不影响**；真正要小心的是接触/摩擦/透明物体的保真度。
- Gazebo Classic 可无头、CPU 运行；对“负样本生成 + 剧本回放 + N 端口 API 排练”足够，对“绝对成功率”不够。

### 0.7 统计功效与杠杆：320 次只够看 +5pp 量级，单轴只有 0.2Δ

- 320 次、p≈0.30 时，单次评测的标准误 **SE=√(0.30×0.70/320)=2.56pp**；95% CI 约 ±5.0pp。
- 两次独立评测的差值 SE≈3.62pp；+5pp 只有 1.4 SE。**必须用配对种子/配对任务**才能把差值 SE 压到 2–3pp；仍不要把单任务 10 次的 +1 次成功当 +10pp（单任务 SE≈14.5pp）。
- 单轴 +Δ 只作用于 2/10 次运行 → 任务级/总平均增益 **0.2Δ**；跨轴执行相位 +Δ 作用于 10/10 次运行，但只有到达该相位的比例 q 能吃到 → **qΔ，q≈0.4–0.8**。跨轴相位的杠杆是单轴的 **2–4 倍**。

## 1. 三个灵感词，各自钉到事实上

### 1.1 群体智能：不是比喻，是决策关键相位上的并行几何搜索

去年以来“test-time scaling”在 VLA 里变成热词，但大多数做法是“采样多个动作块 + 学一个 verifier 选一个”。这条路线有三个问题：verifier 是第二个学习模型（单模型规则风险）、GPU 开销大、延迟抖动。群体智能给的是另一条路：**不学 verifier，用确定性几何适应度；不选动作块，直接在 3-DoF/6-DoF 位姿空间里搜；只在决策关键相位启动，而不是每步都搜。**

证据链：

- **DiVeR**（[S15]）：决策关键性可以用“冻结策略下采样动作的离散度”估计；高离散度状态才是候选选择真正有区别的地方；按关键性重加权 verifier，LIBERO/RoboCasa/真机提升最高 +13.6pp，且 verifier 开销可忽略。→ **DCSG 用“动作离散度”做相位门控**：离散度低就跳过 PSO，离散度高才启动。
- **ELASTIC**（[S16]）：测试时算力应随状态/任务/策略自适应分配；抓取早期适合并行探索，接近接触适合串行精化；真机上匹配 best-of-10 的同时降低 34% 时延。→ **DCSG 在抓取/插入/放置三个相位给不同的 N/迭代/终止阈值**，而不是全局固定。
- **Placeability metric**（[S17]）：从部分点云联合评分**稳定性、可抓性、间隙**，可做无模型、无 CAD 的 6D 放置评估；在非平面支撑/未见物体上给出与 CAD 可比、通常比学习式预测器更物理合理的稳定性判断。→ **DCSG 的适应度直接复用这三类几何项**，再加演示先验/重投影/可达性。
- **FlipToSee**（[S18]）：稳定放置本质上是多峰的；用 vMF 混合密度在 S² 上建模支撑法向，再对候选做鲁棒性重排；零样本到 YCB 90%。→ **DCSG 用粒子群显式保留多峰候选**，再用共识/边际做重排，不回归到单一均值。
- **CorrectVLA**（[S19]）：VLA 的失败里约 22–23% 是“执行幅度失配”（到达了正确目标但量不对），这类失败可以用**冻结权重 + 时间局部的小修正**救回来；语义理解失败则救不了。→ **DCSG 的定位就是“几何/幅度修正”，不碰语义**；这也划清了能力边界。
- **PSO 抓取规划**（[S20][S21]）：粒子群在抓取构型/接触点搜索上已有长期证据；适应度可以是抓取质量、力闭合、Jacobian 条件数等。→ **DCSG 把 PSO 从“离线抓取规划”搬到“在线最后三厘米”**，并把它限制在低维位姿空间。

合起来：**群体智能在这里不是“多采样几次”，而是“在决策关键相位，用一群显式位姿候选去覆盖多峰几何景观，用确定性适应度选，用共识/边际决定敢不敢执行”。**

### 1.2 Gazebo：不是数字孪生，是负样本发生器 + 剧本回放 + API 排练

第 5/7 轮已经证明“全 32 任务高保真孪生”不划算。本轮把 Gazebo 的用途压到三条窄缝：

1. **负样本发生器**：官方 33k 演示是“成功示范（假定成功）”，没有“失败位姿”标签。Gazebo 可以在演示位姿附近做 1–5cm / 5–20° 扰动，模拟翻倒、滑落、碰撞、没插进去，给 DCSG 的几何适应度提供**负样本**，用来拟合权重/阈值。
2. **官方干扰剧本回放**：第 7 轮已从 `info.json` 抓到 `human_1_note`/`human_4_note`（如“把粉色碗向下移动”“叠了第二个之后拿下第二个”“拉上拉链之后拉开”）。Gazebo 可以按这些 1-DOF 剧本回放，测 DCSG 的“重新共识/恢复”逻辑是否成立——**只测逻辑，不测绝对成功率**。
3. **N 端口 API/时延排练**：用 Gazebo 或 mock 客户端起 N 个端口，压 `reset` 隔离、并发、p99、超时；这是提交前的 soak，不是研究实验。

**明确不做**：不把 Gazebo 当真实成功率基准；不用 Gazebo 训练 VLA；不做全任务高保真孪生；不把仿真数据混进训练集。Gazebo 只校准**确定性适应度的权重**，以及排练**服务形态**。

### 1.3 低成本：单卡 24GB + CPU PSO + 不重训 + 不加第二个模型

低成本不是“把模型压小”，而是把**边际算力放在最值钱的地方**：

- **模型**：WLA-1.0-Base 6B，冻结 VLM，只训/复用 action expert；单卡 24GB；4 步去噪。
- **总督**：CPU 上的 3-DoF PSO（N=24，15 iter）——24×15=360 次适应度评估，每次是点/多边形/矩阵运算，目标 <20ms/相位。
- **种子**：官方演示的位姿统计（中位数/MAD）+ 检索段，不需要新数据、不需要新网络。
- **感知**：头部立体对做经典 SGBM（下采样到 240×320）拿稀疏深度；腕部 RGB 做局部校验；不引入 SAM/深度大模型等第二个学习模型。若某任务必须用学习式分割，则作为“工具”披露并做合规开关（默认关）。
- **服务**：N 端口共享一个后端 + 动态 batch；`action_chunk_size` 16–30；p99 目标 <300ms。
- **校准**：Gazebo CPU 无头 + 8 个任务的小场景；正/负样本各几百条；逻辑回归/网格搜索拟合权重；目标 <1 GPU-day。
- **不做的低成本伪命题**：不为了“轻”去蒸馏 0.8B 学生（与“不重训”冲突）；不做神经 Best-of-N（延迟抖动 + 第二模型风险）；不做每任务 LoRA。

## 2. 第 7 轮的三处修正

### 2.1 步骤分是 tie-break，不是主目标

第 7 轮花了很大篇幅论证“放置类步骤约占 59.7%、终局约占 39.8%”，这作为**评分结构描述**是对的；但把它当成优化目标就错了。排名先比成功率。正确表述是：

```text
第一目标：32 任务总平均成功率
第二目标：成功率相同时，总平均步骤分
第三目标：仍相同时，提交日期更早
```

所以 DCSG 的验收标准必须是**成功率**，步骤分只作为“没有牺牲成功率”的副指标；绝不能为了多完成一步而增加失败概率。

### 2.2 终局放置不是唯一瓶颈：逐任务 gap 的异质性

第 7 轮的主判断是“终局放置是 32/32 任务的闸门”。闸门没错，但“唯一瓶颈”不成立。占位数据的逐任务 `step_score − success_rate` 差值（弱先验，[S3]）显示：

| 类型 | 代表任务（gap） | 读法 |
|---|---|---|
| 后段失败为主 | Stack Cups 10.33、Conveyor 9.87、Store Earphones 9.53、Paper Cup 9.52、Photo Frame 9.52、Fruit Basket 9.50 | 已经完成不少步骤，倒在放置/堆叠/收纳 |
| 早段失败为主 | Plug In Ethernet 6.00、Unlock 6.83、Spell Robot 7.48、Organize Stationery 7.63、Open Pill Bottle 7.77、Hang Cup 7.86 | 抓取/对齐/插入/开合没过去，部分分也不高 |

这不是说“终局不重要”，而是说**决策关键相位因任务而异**：叠杯/纸杯/相框/耳机盒是放置相位；插网线/插排/开锁/拉链是插入/关节相位；挂杯/抓水果是抓取相位。DCSG 因此覆盖 **抓取、插入、放置** 三类，而不是只做终局。

### 2.3 单轴补点只有 0.2Δ，跨轴执行相位才是 2–4× 杠杆

第 5 轮的“补最弱轴”算术仍然成立：单轴 +Δ 只影响 2/10 次运行 → 0.2Δ。但第 7 轮没有把“跨轴执行相位”的杠杆算透：

```text
单轴改进：      +Δ × (2/10) = 0.2Δ
跨轴相位改进：  +Δ × q，q = 到达该相位的比例 ≈ 0.4–0.8
杠杆比：        q / 0.2 = 2–4×
```

抓取/插入/放置是**每个轴都要做**的动作，所以它们的改进不挑轴。DCSG 的群体搜索只在这些相位启动，正是把算力放在“跨轴资产”上。

## 3. 主判断：DCSG

### 3.1 一句话

**VLA 提议语义，群体处置几何：在抓取（接触前约 3cm）、插入（座合前约 3cm）、放置（释放前约 3cm）三个决策关键相位，用 VLA 采样 + 演示种子 + 几何扰动生成候选，用确定性几何适应度做 3-DoF 粒子群搜索，用共识/边际门控决定“直接执行 / 慢速伺服 / 回退”，再由 SVL 缓放/校验/重试，由 NRB 处理人为撤销。**

### 3.2 架构

```text

        │
        ▼
SSG 步骤图/相位标签 ──► 相位门控：是否决策关键？
        │                    │
        │              ┌─────┴─────┐
        │              │ 否：直通   │──► WLA chunk（快路径）
        │              └─────┬─────┘
        ▼                    ▼ 是（抓取/插入/放置）
WLA-1.0-Base 采样 K 个 chunk ──► 提取相位末端 EE 位姿
        │
        ▼

        │
        ▼

        │
```

### 3.3 三个决策关键相位

| 相位 | 触发（近似） | 搜索维度 | 主要适应度项 | 执行原语 |
|---|---|---|---|---|
| 抓取 | 夹爪距目标 <3cm、相对速度低、动作离散度高 | x, y, yaw（可扩 z/pitch） | 力闭合/对跖、碰撞、重投影、演示抓取先验、可达性 | 预抓取→闭合→轻抬→校验 |
| 插入 | 末端距孔/座 <3cm、朝向对齐、接触前 | x, y, yaw（可扩 tilt） | 轴对齐、间隙、插入深度、重投影、演示先验 | 对齐→慢速压入→微搜索→到位 |
| 放置 | 物体距支撑/容器 <3cm、释放前 | x, y, yaw（可扩 z） | 支撑多边形/CoM、稳定性、间隙、演示释放先验、重投影 | 慢放→静置→稳定性校验→nudge/regrasp |

相位检测用两路信号：**SSG 步骤图**（第 7 轮保留）给语义相位；**动作离散度**（DiVeR 式）给“这一步是否真的有分歧”。两者都满足才启动 PSO；否则直通 VLA，保证平均时延。

### 3.4 粒子群怎么工作

- 初始化：8 个粒子来自 VLA 采样，8 个来自演示种子（OPT 容器系释放/抓取位姿），8 个来自当前最优种子附近的高斯扰动；低差异初始化，保证多峰覆盖。
- 速度更新：标准 PSO，惯性权重 0.9→0.4 线性衰减，c1=c2=1.5；速度 clamp 到 2cm/iter、10°/iter。
- 适应度：全部是确定性几何量，无学习模型；权重由 Gazebo 正/负样本校准（§4）。
- 终止：达到 max iter，或 gbest 适应度 > τ 且共识 κ > κ0 时早停。
- 共识：取 top-8 粒子，κ = 落在 gbest 1cm/5° 内的比例；margin = top-4 平均适应度 − 次 4 平均适应度。
- 决策：κ≥0.75 且 margin≥m1 → 直接执行；κ≥0.5 → 慢速伺服 + SVL；否则回退。
- 成本：N=24、15 iter、3-DoF；向量化 NumPy，目标 <20ms/相位；每任务最多 3 个相位，总计 <60ms。

### 3.5 共识/边际门控：为什么不是“选最高分就执行”

群体搜索最大的风险不是搜不到好解，而是**在一个错误的适应度景观里自信地选了一个坏解**。共识/边际门控是低成本的安全带：

- 如果 top 粒子聚成一簇（κ 高）且明显优于次优簇（margin 高），说明几何景观清晰，可以快执行。
- 如果 κ 高但 margin 低，说明多个解差不多，执行要慢、要验证。
- 如果 κ 低，说明景观多峰/不确定，宁可回退到 VLA 或保守伺服，也不赌。

这比“取 argmax”多了一层**不确定性显式化**，而且不需要学习模型。

## 4. 为什么这是研究贡献，而不是工程堆料

### 4.1 与最近工作的差异

| 工作 | 它做了什么 | DCSG 的不同 |
|---|---|---|
| DiVeR [S15] | 学一个决策关键性加权的 verifier，选动作块 | DCSG **不学 verifier**；用确定性几何适应度；搜的是 3-DoF 位姿，不是动作块 |
| ELASTIC [S16] | 学一个 meta-policy 分配串行/并行算力 | DCSG 用**固定相位 + 动作离散度门控**，不训练 meta-policy；算力只花在三个相位 |
| Placeability [S17] | 用稳定性/可抓性/间隙评估 6D 放置 | DCSG 把它当**适应度项之一**，加演示先验/重投影/可达性，并用 PSO 搜索多峰 |
| FlipToSee [S18] | 学多峰放置先验 + 鲁棒性重排 | DCSG **不学先验**；用官方演示种子 + PSO 显式搜索；用共识/边际替代学习式重排 |
| CorrectVLA [S19] | 用语言反馈做冻结策略的幅度修正 | DCSG 修的是**几何位姿**，不需要人类语言反馈；但共享“执行失配是可修正子集”的判断 |
| PSO 抓取 [S20][S21] | 离线搜索抓取构型/接触点 | DCSG 把 PSO 变成**在线、相位门控、VLA 种子化、共识门控**的运行时组件 |

一句话：**DCSG 的新意不在“用 PSO”，而在“把群体搜索限制在决策关键相位、用官方演示做种子、用确定性几何做适应度、用共识/边际做安全门控、用 Gazebo 做负样本校准”——这套组合在单模型/单卡/不重训约束下是可落地的。**

### 4.2 可证伪假设

- **H1（放置）**：在 StackBowls/PaperCup/PhotoFrame/StoreEarphones 等放置类任务上，DCSG 相对同底座基线 **+5pp 成功率**，且超时率不升。
- **H2（插入）**：在 PlugCharger/PlugEthernet/Unlock/ZipUp/OrganizePencilCase 等插入/关节类任务上，DCSG **+5pp**，且重试次数/碰撞代理指标下降。
- **H3（时延）**：相位门控 PSO 的 p99 增量 <60ms/任务，端到端 p99 <300ms；always-on PSO 更慢且无额外收益。
- **H4（Gazebo 校准）**：Gazebo 负样本拟合的权重在留出任务上优于手工权重（AUC +0.1）；若否，放弃 Gazebo 校准，保留手工权重。
- **H5（种子）**：演示种子 + VLA 种子 > 仅 VLA > 随机初始化；若否，简化种子库。
- **H6（门控）**：共识/边际门控相对“永远执行 gbest”显著降低负样本上的灾难性执行率；若否，门控只是装饰。

### 4.3 预期收益与统计功效

- 目标不是“承诺 +10pp”，而是**在 320 次真机上可测的 +5pp 量级**；放置/插入子集目标 +5–8pp，整体 +3–6pp。
- 320 次、p≈0.30：SE≈2.56pp；配对设计下差值 SE 可压到 ~2pp；+5pp 才有 ~2.5 SE 的说服力。单任务 10 次 SE≈14.5pp，**不要用单任务调参结果下结论**。
- 如果真实 baseline 只有 20–30%，+5pp 相对提升约 17–25%，在排行榜上是有意义的；但真实榜未发布，所有收益都是假设，必须用调试槽/计分跑验证。

### 1.3 接口：N 端口、共享后端、状态隔离、时延记录

`unibot_submission` README（[S9]）：

- 评测在 **N 台机器人**上随机顺序进行；N 由官方另行公布；必须暴露 **N 个连续端口**（8765…8765+N−1），端口数必须与 N 完全一致。

## 2. 评分算术：为什么是“成功率优先 + 三相位跨轴”

### 2.1 目标函数

```text
主目标：S = (1/32) Σ_t s_t，s_t = 任务 t 的 10 次运行平均成功率
次目标：P = (1/32) Σ_t p_t，p_t = 任务 t 的 10 次运行平均步骤分
再平手：提交日期更早者靠前
```

### 2.2 统计功效

```text
单次评测（320 episodes，p≈0.30 为占位先验，真实 p 未知）：
  SE = sqrt(0.30 × 0.70 / 320) = 2.56pp
  95% CI ≈ ±5.0pp

两次独立评测的差值：
  SE_diff = sqrt(2) × 2.56 = 3.62pp
  配对设计（同任务/同种子/同初始条件）可把 SE_diff 压到 ~2pp

单任务 10 次：
  SE = sqrt(0.30 × 0.70 / 10) = 14.5pp
```

→ 320 次只够看 **+5pp 量级**；单任务 +1 次成功不是 +10pp 证据。实验必须配对、预注册主指标、用 bootstrap CI。

### 2.3 单轴 vs 跨轴

```text
单轴 +Δ：     作用 2/10 次运行 → 0.2Δ
跨轴相位 +Δ： 作用 10/10 次运行，但只有到达该相位的 q 能吃到 → qΔ
杠杆比：      q / 0.2 = 2–4×（q≈0.4–0.8）
```

抓取/插入/放置是每个轴都要做的动作，所以它们的改进不挑轴；这是 DCSG 选择三相位而不是“补最弱轴”的根本原因。

### 3.2 PDG：相位与决策门控

输入：

- SSG 当前步骤 `s_t` 与相位标签（grasp / insert / place / close / pour / other）。
- 动作离散度 `d_t`：冻结 WLA 下采样 K 个 chunk，取相位末端 EE 位姿的离散度（位置 std + 角度 std 的归一化和）。
- 接近度 `p_t`：末端到目标/支撑/孔的估计距离（头部立体深度 + 腕部 RGB）。
- 任务难度/历史：该任务在该相位的失败率（来自离线回放/调试槽，可选）。

规则（可调）：

```text
decision_critical = (phase ∈ {grasp, insert, place})
                    and p_t < 3cm
                    and d_t > d0
```

- `d_t` 低 = 策略很确定，PSO 大概率只是重复 VLA 的解 → 跳过，省时延。
- `d_t` 高 = 策略在多峰之间犹豫 → 正是群体搜索有价值的地方（DiVeR 的决策关键性直觉 [S15]）。
- `p_t` 远 = 还没到最后三厘米 → 先走 VLA 运输段，避免在自由空间浪费 PSO。

### 3.3 DSB：演示种子库

对每个任务/相位，离线构建：

```text
H_i = (T_B^{R_i})^{-1} · T_B^{G_i}(t_i^phase)     # 容器/目标系下的相位末端 EE 位姿
```

- `T_B^{R_i}`：容器/目标坐标系（由标定 + 6D 位姿/关键点估计）。
- `T_B^{G_i}(t_i^phase)`：演示在抓取/插入/释放时刻的 EE 位姿（数据集直接有 `*_ee_pose_gripper_base`）。
- 统计：`H̄ = median_i(H_i.xyz)`；旋转用四元数弦均值或 L2 投影均值；`σ = MAD_i`；`τ_task` 用同任务演示间 95 分位差。

在线种子：

1. **VLA 种子**（8 个）：从 K 个 chunk 的相位末端位姿取 8 个（或聚类中心）。
2. **演示种子**（8 个）：按 ICR 关系键检索 K 条行为对齐演示，取 `T̂_B^R · H_i`（`T̂_B^R` 为当前容器/目标估计）。
3. **扰动种子**（8 个）：在最优种子的 1–3cm / 5–15° 内高斯采样，低差异初始化。

> 为什么不是“动作块复制”：迁移的是**相对位姿统计**，不是轨迹；零梯度、可缓存、跨外观/背景/位置。对应第 7 轮 OPT/ICR 的证据链。

### 3.4 GAF：几何适应度

候选位姿 `x = (x, y, θ)`（抓取/插入/放置；必要时扩到 z/pitch/tilt）：

```text
F(x) = w_s S(x) + w_c C(x) + w_r R(x) + w_d D(x) + w_a A(x) + w_k K(x)
```

| 项 | 含义 | 计算（确定性） | 证据/备注 |
|---|---|---|---|
| `S` 支撑/稳定 | 放置：投影 CoM 在支撑多边形内 + 边距；抓取：对跖/力闭合质量；插入：轴/面接触稳定 | 点云/多边形/法向；无学习 | Placeability 的 stability/graspability [S17] |
| `C` 间隙/碰撞 | 到容器壁/障碍/其他物体的 signed distance；碰撞惩罚 | 立体深度/简化几何；胶囊/包围盒 | Placeability 的 clearance [S17] |
| `R` 重投影 | 候选 3D 位姿在多头/腕相机上的 2D 检测一致性 | 投影 + 2D 轮廓/关键点误差 | 多视图一致性；无学习 |
| `D` 演示先验 | 到检索到的 K 条演示位姿的 Mahalanobis 距离 | `H_i` 统计查表 | OPT/ICR [S22 第 7 轮] |
| `A` 对齐 | 与容器/目标轴、重力方向、槽位方向的夹角 | 几何 | 放置/插入 |
| `K` 可达 | IK 残差 / 关节限位余量 | 解析/数值 IK | 双臂 G1 |

权重 `w_*` 的来源：

- 初值：手工（等权/经验）。
- 校准：Gazebo 正/负样本 → 逻辑回归/排序学习/网格搜索（§4）。
- 归一化：每项先映射到 `[0,1]`，避免量纲主导。

> **关键合规点**：GAF 不含学习模型；感知只用经典立体/几何/颜色/轮廓。若某任务必须用学习式分割，作为“工具”披露并默认关闭。

### 3.5 PSO：伪代码与超参

```python
def dcsg(phase, obs, seeds):
    swarm = init_particles(seeds, n=24)
    pbest = swarm.copy(); pbest_f = [-inf]*24
    gbest, gbest_f = None, -inf
    w = 0.9
    for it in range(15):

            f = GAF(x, phase, obs, seeds)
            if f > pbest_f[i]:
                pbest[i], pbest_f[i] = x, f
            if f > gbest_f:
                gbest, gbest_f = x, f
        for i in range(24):
            r1, r2 = rand(), rand()
            v = (w*vel[i]
                 + 1.5*r1*(pbest[i]-swarm[i])
                 + 1.5*r2*(gbest-swarm[i]))
            vel[i] = clamp(v, 2cm, 10deg)
            swarm[i] = clamp(swarm[i]+vel[i], bounds)
        w = max(0.4, w - 0.033)
        if gbest_f > tau and consensus(swarm, gbest) > kappa0:
            break
    kappa, margin = consensus_margin(swarm, gbest)
    return gbest, kappa, margin
```

超参（初值，待校准）：

| 参数 | 值 | 理由 |
|---|---:|---|
| N | 24 | 3-DoF 的覆盖/成本折中；可消融 8/16/24/32 |
| iters | 15 | 15×24=360 次评估；目标 <20ms |
| ω | 0.9→0.4 | 标准线性衰减 |
| c1=c2 | 1.5 | 标准 PSO |
| v clamp | 2cm / 10° | 防止粒子飞出局部 |
| κ0 | 0.75 | 高共识才早停 |
| τ | 0.8（归一化） | 足够好才早停 |

> 向量化：24 个粒子 × 6 项几何，NumPy 批量；避免 Python 循环里的逐点云操作；点云下采样到 2–3k 点。

### 3.6 共识/边际门控

```text
top = sorted(swarm, key=F, reverse=True)[:8]
κ = fraction(top within 1cm / 5° of gbest)
margin = mean(F[top[:4]]) - mean(F[top[4:8]])
```

决策：

| 条件 | 动作 | 理由 |
|---|---|---|
| κ ≥ 0.75 且 margin ≥ m1 | 执行 gbest（快） | 景观清晰，低风险 |
| κ ≥ 0.50 | 执行 gbest + 慢速伺服 + SVL | 有共识但不够强，验证兜底 |
| κ < 0.50 | 回退 VLA chunk / 锚点伺服 / 保守放置 | 多峰/不确定，不赌 |

`m1` 由 Gazebo 负样本校准（例如 0.1–0.2 归一化适应度差）。门控的目标不是“提高平均分”，而是**降低灾难性执行率**（H6）。

### 3.7 SVL：执行层

```python
def execute(target, slow, phase, budget=2):
    for attempt in range(budget+1):
        stream = policy.track_ee(target, slow=slow)   # 位置目标流
        for cmd in stream:
            send(cmd)
            if reached(target, obs): break
        if phase == "place":
            open_gripper(slow=True); sleep(0.5)
        if stable(phase, obs, window=0.5) and predicate_met(phase, obs):
            return True
        if repairable(phase, obs):
            target = nudge(target, obs)
        else:
            regrasp(phase)
    return False
```

- `stable`：物体相对位姿 0.5s 内位移 <ε_rel + 谓词保持。
- `predicate_met`：SSG 谓词头 + 事件（接触/静止/到位）。
- 预算：普通任务 ≤2 次；长程任务（T16/T17/T31）≤1 次；Endurance Governor 兜底 180s。

### 3.8 NRB：人为撤销恢复

用官方 `human_1_note`/`human_4_note` 构造/回放：

| 任务 | 官方备注（节选） | 场景化 | 恢复目标 |
|---|---|---|---|
| StackBowls | 叠了第二个之后拿下第二个 | 移除 bowl2 | 重新放置 bowl2 → 继续 bowl3 |
| ZipUp | 拉上拉链之后拉开 | 拉开拉链 | 重新拉合 |
| PourOutMedicine | 拧开盖子之后拧动回来 | 盖回瓶盖 | 再拧开 → 倒药 |
| OrganizeStationery | 笔盒合上之后手动打开 | 打开盒盖 | 重新合上 |
| ConveyorSorting | 物品快到了然后放回传送带起点 | 目标远离 | 重新抓取→放置 |
| PlugCharger | 将插头拔起 | 拔出插头 | 重新抓取→插入 |
| Unlock | 中途把锁拿走 | 锁被移走 | 重新定位锁→继续翻环 |

触发：SSG 谓词从 1→0（被撤销/移走）→ 重置相位 `s_t` → 重新走 PDG/DCSG/SVL。NRB 不是新模型，是事件表 + 恢复策略。

### 3.9 与 WLA 的接口

- **动作空间**：EE（base 系 `xyz+rpy`），与 DCSG 的位姿目标天然一致。
- **chunk**：WLA 输出 30 步 horizon；DCSG 只改写相位末端的若干步（例如最后 5–10 步），其余保持 VLA 输出。
- **观测**：`obs_delta_indices` 传四路 RGB + EE/夹爪/关节；`image_resize` 可把头部降到 240×320 做立体，腕部保持 480×640 做局部校验。
- **语言**：SSG 精确匹配 160 条复述 + 规范化 + 嵌入兜底；DCSG 不改语言。

## 4. Gazebo 校准（GCal）

### 4.1 为什么是 Gazebo，为什么只做窄用

- 官方 33k 演示是**成功示范（假定成功，未逐条标注）**，没有失败位姿标签；GAF 的权重/阈值需要负样本。
- Gazebo 可以在演示位姿附近做扰动，快速生成“翻倒/滑落/碰撞/没插进去”的负样本；CPU 无头即可，成本低。
- G1+Dex1 的 URDF 现成（`g1_29dof_mode_15_with_dex1_1.urdf`）；桌面任务基座固定，不需要行走。
- **不做什么**：不做全 32 任务高保真孪生；不用 Gazebo 绝对成功率做验收；不把仿真数据混进训练；不做透明/布料的全物理。

### 4.2 场景集

首轮 8 个任务（覆盖三相位 + 刚体/容器）：

| 任务 | 相位重点 | 场景要素 |
|---|---|---|
| StackBowls | 放置/堆叠 | 3 个碗、桌面、支架/托盘 |
| PaperCupStacking | 放置/堆叠 | 3 个纸杯、桌面 |
| PlacePhotoFrame | 放置/摆正 | 相框、支架、桌面 |
| StoreEarphones | 放置/闭合 | 耳机盒、托盘、收纳盒 |
| PlugCharger | 插入 | 插排、插头、桌面 |
| PlugInEthernet | 插入 | 网线、网口、桌面 |
| HangCup | 抓取/挂 | 杯子、挂钩架 |
| ArrangePlates | 放置 | 盘子、架子 |

其中 6 个用于拟合，2 个留出（例如 StackBowls + PlugInEthernet 留出），避免“权重只对这 8 个任务好”。

### 4.3 正/负样本生成

**正样本**：

1. 从官方演示随机抽 200 条/任务，取抓取/插入/释放时刻的 EE 位姿与物体位姿。
2. 在 Gazebo 里把物体放到演示位姿，机器人执行该相位末端位姿（或直接把物体放到目标位姿并施加小扰动）。
3. 模拟 1s；记录是否稳定/无碰撞/到位。

**负样本**：

1. 对正样本位姿加 1–5cm / 5–20° 扰动。
2. 模拟 1s；记录失败模式：翻倒、滑落、碰撞、未插入、弹出。
3. 每任务 200–400 条负样本；类别均衡。

**标签**：`y=1` 稳定且无碰撞；`y=0` 失败。用 GAF 的 6 项特征拟合逻辑回归/梯度提升（**只用于离线拟合权重，运行时是固定常数，不构成第二个推理模型**）；或网格搜索权重最大化 AUC。

### 4.4 校准与验证

```text
拟合：6 个任务 × (200 正 + 300 负) → 逻辑回归 → w_*
验证：2 个留出任务 → AUC / accuracy / calibration curve
消融：去掉任一项 → AUC 下降多少
稳定：不同随机种子/扰动幅度 → 权重排序是否稳定
```

验收：

- 留出任务 AUC ≥ 0.75（目标 0.8+）。
- 去掉“演示先验”或“间隙”后 AUC 明显下降（证明每项有用）。
- 权重排序在两次独立采样中一致（Spearman ≥ 0.7）。

### 4.5 API/时延排练

- 起 N 个端口（例如 N=3：8765–8767），共享一个后端；用 Gazebo 或 mock 客户端并发调用。
- 检查：`reset` 隔离（端口 A 的 reset 不影响端口 B 的历史）、并发不互相阻塞、p50/p99、超时、动作内容无异常。
- 记录：每步时延、波动、动作统计；与官方“结果可信度”检查对齐。

### 4.6 sim-to-real 的诚实边界

- Gazebo 的接触/摩擦/透明物体与真机有差距；因此**只用相对校准**（哪个权重更好、哪个阈值更稳），不用绝对成功率。
- 留出任务 + 真机调试槽是最终裁判；如果 Gazebo 方向与真机相反，弃用 GCal，回退手工权重。
- 透明/布料任务（T14/T16/T19/T23/T31 等）不做 Gazebo 物理校准，只用演示先验 + SVL。

### 5.3 N 端口服务

```text

```

- 共享后端是官方允许的省卡方式；但必须处理并发与状态隔离（[S9]）。

- 健康检查：每端口一个 `/health`；启动时校验 token；soak 至少 30min。

### 5.4 内存/算力

- WLA 6B bf16 ≈ 12GB；激活/缓存 ≈ 4–6GB；总计 <20GB，留 4GB 余量。
- PSO/立体/检索 <2GB；演示位姿索引 <1GB。
- 不加载第二个学习模型；不加载世界模型；不做全量视频解码（只取需要的帧）。

## 8. 创新点清单（持续迭代；动机/差异/可行性/资源/步骤/风险/状态）

> 状态：押注=本轮主线；保留=沿用；升级=旧点改造；降级=保留但非主回路；砍=不做。

### I1 DCSG 决策关键相位群体总督（新增，押注）
- 动机：VLA 的语义够用，失败集中在最后三厘米的几何决策；320 次只够看 +5pp，必须把算力放在跨轴相位。
- 差异：不是“多采样 + 学 verifier”，而是“确定性几何适应度 + 3-DoF PSO + 共识/边际门控”；不是每步都搜，只在三相位搜。
- 可行性：CPU、无梯度、无新数据；WLA 原生 EE；接口允许。
- 资源：单卡 24GB + 16 核 CPU；PSO <60ms/3 相位（每相位 <20ms）。
- 步骤：PDG → DSB → GAF → PSO → 门控 → SVL 接线。
- 风险：适应度与真实成功不相关 → GCal/留出/调试槽；回退 VLA。
- 状态：押注。

### I2 动作离散度相位门控（新增）
- 动机：DiVeR 证明决策关键性可由冻结策略的采样离散度估计 [S15]。
- 差异：不训练 verifier；只把离散度当“是否启动 PSO”的开关；与 SSG 语义相位双门控。
- 可行性：WLA 采样 K 个 chunk 即可；CPU 统计。
- 资源：K=8 的采样开销；可与 WLA batch 合并。
- 步骤：采样 → 相位末端位姿 → 离散度 → 阈值校准。
- 风险：离散度阈值任务相关 → 分任务/分相位校准；回退 always-on。
- 状态：押注（DCSG 的一部分）。

### I3 演示种子化 PSO（新增）
- 动机：官方 33k 有成功 EE 位姿；比随机初始化更接近真解。
- 差异：种子 = VLA 采样 + OPT 容器系统计 + ICR 检索段 + 扰动；不是纯随机/纯 VLA。
- 可行性：数据字段齐；离线建库；在线查表。
- 资源：位姿库 <1GB；检索 <5ms。
- 步骤：OPT/ICR → 种子生成 → 低差异初始化 → 消融。
- 风险：演示位姿噪声 → 中位数/MAD/离群过滤；τ_task 分位。
- 状态：押注（DCSG 的一部分）。

### I4 共识/边际门控（新增）
- 动机：群体搜索最大的风险是“在错误景观里自信地选坏解”。
- 差异：用粒子簇的 κ 与 margin 决定“执行/慢伺服/回退”，不是 argmax。
- 可行性：PSO 副产品；无额外算力。
- 资源：无。
- 步骤：κ/margin 定义 → 负样本校准 → 门控策略 → 消融。
- 风险：门控过保守 → 回退太多；用调试槽调阈值。
- 状态：押注（DCSG 的一部分）。

### I5 Gazebo 负样本校准（新增，工程/研究混合）
- 动机：官方只有成功演示；GAF 需要负样本。
- 差异：不做全孪生；只做 8 任务正/负样本 + 权重拟合 + 留出验证 + API 排练。
- 可行性：URDF 现成；CPU 无头；成本低。
- 资源：8 任务小场景；<1 GPU-day。
- 步骤：场景 → 正/负样本 → 拟合 → 留出 → 消融。
- 风险：sim-to-real；只用相对校准；真机相反则弃用。
- 状态：新增（中优先；可降级为手工权重）。

### I6 SVL 执行层（保留，升级）
- 动机：PSO 只给目标，执行仍需慢放/校验/修复。
- 差异：从“放置闭环”扩到抓取/插入/放置三相位。
- 可行性：腕部 RGB + 谓词；180s 预算够。
- 资源：无新数据。
- 步骤：稳定性检测 → 修复动作库 → 预算守卫。
- 风险：耗时/误判 → 双阈值 + 长程限 1 次。
- 状态：保留。

### I7 NRB 官方剧本恢复（保留）
- 动机：human 轴备注公开，且多为 1-DOF 平移/撤销。
- 差异：官方剧本忠实回放 + 通用扰动兜底。
- 可行性：备注多为刚体变换；合成/回放便宜。
- 资源：ACP/2.5D 管线（第 5 轮）。
- 步骤：备注表 → 场景脚本 → 恢复对 → 事件触发。
- 风险：编号含义未核实 → 同时覆盖通用扰动。
- 状态：保留。

### I8 SSG/OPT/PGL/ICR（保留，降为基础设施）
- 作用：相位标签、演示位姿统计、锚点渲染、检索种子。
- 差异：不再承担主创新；为 DCSG 服务。
- 风险：复杂度 → 按需启用；可单独关闭。
- 状态：保留。

### I9 低成本 N 端口服务（保留）
- 作用：共享后端 + 动态 batch + 状态隔离 + 时延守卫。
- 差异：官方允许；省卡；但必须做隔离/并发。
- 风险：串扰/拥塞 → session_id + 队列 + soak。
- 状态：保留。

### I10 配对统计协议（新增，流程）
- 作用：320 次只够 +5pp；用配对/预注册/bootstrap 避免自欺。
- 差异：把“统计功效”写进实验设计，而不是事后解释。
- 风险：配对不可行 → 用任务分层 + 更大样本。
- 状态：新增。

### 已砍清单（跨轮）
- 全 32 任务高保真孪生；自由仿真数据；运行时仿真/MPC；仿真 RL；WMD 世界模型蒸馏；每任务 LoRA/模型合并；在线世界模型；神经 Best-of-N verifier；多模型 ensemble；任务硬编码坐标；力控/阻抗控制宣称（API 不支持）。

## 12. 一句话押注

**在成功率优先、单模型、单卡 24GB、320 次真机的约束下，把 VLA 的“最后三厘米”交给一个只在决策关键相位启动的 CPU 粒子群几何总督（DCSG）：用官方演示做种子、用确定性几何做适应度、用共识/边际做门控、用 Gazebo 负样本校准权重、用 SVL/NRB 做执行与恢复；不重训、不加第二个学习模型、不做全任务孪生。**
