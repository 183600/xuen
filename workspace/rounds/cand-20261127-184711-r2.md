### 灵感驱动研究记录 · 本轮：跌倒恢复 × 可解释性

**灵感词**：跌倒恢复、可解释性

**直觉与动机（先讲直觉）**：

前几轮把机器人控制做成了一条「正向证书链」：动作 → 证书 → 准入，证据不足就不执行。但这条链在最危险的时刻——跌倒——恰恰是断的。现有 CADVS 在证书失败时大多只能「急停 / 切教师」，把跌倒当作不可恢复的终态；而真实的双足/人形机器人跌倒恢复，需要在几百毫秒内回答三个问题：

1. **我是不是真的在倒？**（检测：迟报会错过恢复窗口，误报会诱发不必要的翻滚）
2. **我现在还救得回来吗？用哪种姿势救？**（可恢复性判定 + 策略选择：撑地、屈膝、侧滚卸力、坐起、扶墙）
3. **为什么倒的？为什么选这个救法？**（因果解释：是脚滑、被推、执行器饱和，还是地形突变？）

直觉上，**跌倒恢复与可解释性是同一件事的两面**。恢复策略的选择本质上是对「跌倒原因」的一次押注：被推倒时顺势侧滚卸力、脚滑时先降重心找摩擦、执行器饱和时用手撑地再撑起、地形塌陷时优先扩大支撑面。**选错原因，就会选错恢复动作**。因此「解释」不是跌倒后的公关报告，而是恢复决策的输入；「恢复」也不是盲目动作序列，而是一个可被证书检验的因果假设。二者合起来形成闭环：**用因果解释证书驱动恢复策略，用恢复结果反过来证伪/证实解释**。

**关键洞见**：现有 CADVS 只有「正向证据链」（动作→证书→准入），跌倒恢复需要补一条「反向证据链」（结果→原因→反事实→下一次动作）。可解释性在这里的价值不是给人看的热力图，而是**可反驳的因果假设**：每条解释都附带「若把变量集合 S 改掉，跌倒就不会发生」的反事实预测，并能在回放/仿真中被验证。恢复成功后，这条解释被记入账本，成为跨跌倒事件的学习与校准信号；恢复失败则暴露解释的模型盲区。

**严谨定义（从直觉到形式）**：

1. **跌倒 = 可行域退出**。设直立可行集 K_up ⊂ X 为最大受控不变集（存在策略使轨迹对所有扰动 w∈W 都留在其中）。跌倒时刻 t_f = inf{ t : x(t) ∉ K_up }。定义可行裕度 m(x) 为状态 x 到 K_up 边界的符号距离；m(x)<0 即已离开直立可行域。
2. **可恢复性 = 回到 K_up 的受控可达性**。设跌倒后状态 x_f ∈ F（跌倒集），恢复时间预算 T_rec。恢复可行核 RV = { x ∈ F : ∃π, ∀w∈W, ∃t≤T_rec, x(t) ∈ K_up }。可恢复裕度 ρ_rec(x) = LCB(V_rec(x)) − V_min，其中 V_rec(x) 为「在 T_rec 内恢复成功」的价值函数，LCB 由价值集成（复用 ValueNode 的 ensemble）给出；ρ_rec>0 表示以证书级置信度仍可恢复。
3. **解释 = 结构因果模型上的充分原因**。设 SCM M=(V,U,F_M)，V 含姿态、速度、接触、地形、控制指令、KC 激活等变量，U 为外生扰动（推、滑、负载）。对跌倒事件 φ，集合 S⊆V 是**充分原因**，若存在干预 do(S=s′)（s′≠s）使 φ 在其余变量的事实邻域 N_ε 内恒为假；因果强度 κ(S) 为翻转 φ 的干预集合测度。最小充分原因 S* = argmin |S|。解释证书 CEC = (S*, s, s′, ε, κ, 验证轨迹集)。
4. **解释驱动恢复**。恢复策略 π_rec(u | x, CEC) 以因果解释为条件；策略库 Σ 中每个策略 σ 带前置条件 Pre(σ) 与后置证书 Post(σ)。选择 σ* = argmax_{σ : Pre(σ)(x,CEC)} [ ρ_rec^σ(x) + β·match(σ,CEC) − γ·risk(σ,CEC) ]，即「可恢复性 × 因果匹配 − 残余风险」。
5. **解释的可靠性度量**：忠实度（解释能预测反事实结果）、可靠性/可验证率（CEC 在仿真回放中通过的比例）、稳定性（相似跌倒给相似解释）、可操作性（解释指向可控变量而非不可控外因）、时效性（在恢复窗口内产出）。

**形式化目标（增量）**：

- **FEC**（跌倒事件证书）：检测延迟 δ_det、误报率、跌倒类型初判与置信度；
- **RVC**（恢复可行证书）：ρ_rec、witness 恢复策略、成功概率下界 1−δ；
- **CEC**（反事实解释证书）：最小充分原因、因果强度 κ、可验证反事实轨迹；
- **CCRP**（原因条件恢复策略）：以 CEC 为条件的策略库选择与恢复中再跌倒监控；
- **ERLTM**（解释-恢复账本与信任监控）：解释与恢复结果一致性回写、解释漂移检测、低置信度时请求人类介入；
- **理论增量**：FEC 检测延迟/误报界（CUSUM）、RVC 可靠性下界、CEC 在模型误差下的近似可靠性、解释-恢复一致性命题、CIFR 执行集安全性；
- **实验增量**：仿真 + 真机，恢复成功率、再跌倒率、解释可验证率、解释延迟、人机信任校准。

**与既有框架的关系**：CIFR（Certificate-driven Interpretable Fall-Recovery）不是替换 CADVS，而是在其十二证之上追加跌倒分支的三张证（FEC/RVC/CEC），并把 RCANG 从 7 节点扩为 9 节点（新增 RecoveryNode、ExplainNode）。正常行走路径的证书集与执行集保持不变，只有 FEC 触发后才进入恢复分支。

**本轮最大风险**：**模型自指的解释失效**——我们被迫用「未能预见这次跌倒」的同一个世界模型去生成跌倒原因的因果证书；在分布外跌倒上，该模型既漏掉了真正的致因变量，又会以高置信度给出一个自洽但错误的解释，进而把恢复策略引向错误动作。这种「被认证的错误理解」比没有解释更危险。

### IP-478 Fall Event Certificate (FEC)

```python
@dataclass
class FallEventCertificate:
    """FEC：可行裕度 CUSUM 检测 + 跌倒类型初判。"""
    cusum_k: float = 0.5          # CUSUM 参考值（裕度单位/步）
    cusum_h: float = 5.0          # CUSUM 判决阈值
    min_dwell: int = 3            # 连续负裕度最小驻留
    margin_floor: float = -0.05   # 硬触发：裕度低于此值立即触发

    def __post_init__(self):
        self.g = 0.0
        self.dwell = 0
        self.triggered = False

    def update(self, x: State, contact: ContactPattern, t: float) -> FEC | None:
        m = self._viability_margin(x)            # 到 ∂K_up 的符号距离
        # 单边 CUSUM：裕度下降方向累积证据
        self.g = max(0.0, self.g + (self.margin_floor - m) - self.cusum_k)
        self.dwell = self.dwell + 1 if m < 0 else 0

        hard = m < self.margin_floor
        soft = (self.g > self.cusum_h) and (self.dwell >= self.min_dwell)
        if not self.triggered and (hard or soft):
            self.triggered = True
            return FEC(
                t_f=t, det_delay=self._estimate_delay(self.g),
                m_f=m, type=self._classify_fall(x, contact),
                conf=self._confidence(self.g, m),
            )
        return None

    def _classify_fall(self, x, contact) -> str:
        # 依据接触模式 + 躯干速度方向做初判（供 CEC 先验）
        if contact.is_push_impulse and x.v_com > self.v_thresh:
            return 'pushed'
        if contact.is_slip and x.contact_friction < self.mu_min:
            return 'slipped'
        if x.tau_saturated or x.actuator_health < 0.5:
            return 'actuator_fault'
        if x.terrain_drop > self.drop_thresh:
            return 'terrain_collapse'
        return 'unknown'
```

**检测延迟/误报**：FEC 的判决等价于对 `margin_floor − m` 的单边 CUSUM。跌倒后若裕度每步平均下降 Δ>cusum_k，则期望检测延迟约为 `cusum_h/(Δ−cusum_k)`；在无跌倒（H0）下，高斯噪声的误报平均运行长度约 `exp(2·cusum_k·cusum_h/σ²)`。工程上以 `cusum_h` 调节「早报 vs 误报」的帕累托前沿（见引理 32）。

### IP-479 Recovery Viability Certificate (RVC)

```python
@dataclass
class RecoveryViabilityCertificate:
    """RVC：集成 LCB 可恢复裕度 + witness 策略 + 成功概率下界。"""
    T_rec: float = 2.5
    V_min: float = 0.60           # 恢复成功概率可接受下界
    z: float = 1.96               # LCB 置信系数
    n_ensemble: int = 5

    def recoverability(self, x: State, sigma: str,
                       value_ensemble: ValueEnsemble) -> RVCResult:
        # value_ensemble 输出 N 个恢复成功概率（同一策略、不同扰动采样/模型头）
        samples = value_ensemble.predict_recovery(x, sigma, horizon=self.T_rec)
        mu, sd = samples.mean(), samples.std(ddof=1)
        lcb = mu - self.z * sd / np.sqrt(len(samples))
        rho = lcb - self.V_min
        return RVCResult(
            strategy=sigma, rho=rho, success_lcb=lcb,
            delta=1.0 - lcb, witness=self._witness(x, sigma),
            valid=(rho > 0.0),
        )

    def _witness(self, x, sigma) -> np.ndarray:
        """witness：一条在标称模型下成功恢复的开环动作序列，供回放核验。"""
        return self._nominal_plan(x, sigma, self.T_rec)

    def certify(self, x: State, cec: CEC,
                value_ensemble: ValueEnsemble) -> list[RVCResult]:
        out = []
        for name, sigma in STRATEGIES.items():
            if not sigma.pre(x, cec):        # 前置条件不满足直接淘汰
                continue
            out.append(self.recoverability(x, name, value_ensemble))
        return out
```

### IP-480 Counterfactual Explanation Certificate (CEC)

```python
@dataclass
class CounterfactualExplanationCertificate:
    """CEC：SCM 上的最小充分原因 + 反事实验证。"""
    scm: StructuralCausalModel
    eps_model: float = 0.05       # 模型误差上界
    eps_ball: float = 0.10        # 事实邻域半径 N_ε
    max_set_size: int = 3
    n_cf: int = 64                # 每个候选集的反事实采样数

    def explain(self, tau: Trajectory, fec: FEC) -> CEC:
        cands = self._candidate_causes(tau, fec)   # 先验排序：可控性 + 梯度显著性
        for k in range(1, self.max_set_size + 1):
            for S in itertools.combinations(cands, k):
                s_fact = {v: tau.value(v, fec.t_f) for v in S}
                s_cf = self._propose_intervention(S, tau, fec)  # 使 φ 翻转的候选干预
                if s_cf is None:
                    continue
                ver = self._verify(S, s_cf, tau, fec)           # 批量反事实回放
                if ver.sufficient:
                    kappa = self._causal_strength(S, s_cf, tau, fec)
                    return CEC(S=list(S), s=s_fact, s_cf=s_cf,
                               eps=self.eps_ball, kappa=kappa,
                               cf_trajectories=ver.trajectories)
        return CEC.unexplained(reason='no_sufficient_cause_within_budget')

    def _verify(self, S, s_cf, tau, fec) -> Verification:
        """在 do(S=s_cf) 下，对 V\\S 的事实值做 ε-ball 采样并回放；
        若所有样本都不发生跌倒（φ 恒假），则 S 为充分原因。"""
        trajs, ok = [], True
        for _ in range(self.n_cf):
            v_other = self._sample_eps_ball(tau, exclude=S, radius=self.eps_ball)
            x0 = self._fallen_state(tau, fec.t_f)
            tr = self.scm.rollout(x0, do={**s_cf, **v_other},
                                  horizon=fec.t_f + self.T_roll)
            trajs.append(tr)
            if tr.fell:               # 只要有一个反事实仍跌倒，就不充分
                ok = False
                break
        return Verification(sufficient=ok, trajectories=trajs)

    def _causal_strength(self, S, s_cf, tau, fec) -> float:
        """κ(S)：在 S 的干预空间内随机采样，统计翻转 φ 的比例。"""
        flips = 0
        for _ in range(self.n_cf):
            s_rand = self._sample_intervention(S)
            tr = self.scm.rollout(self._fallen_state(tau, fec.t_f),
                                  do=s_rand, horizon=fec.t_f + self.T_roll)
            flips += int(not tr.fell)
        return flips / self.n_cf
```

### IP-481 Cause-Conditioned Recovery Policy (CCRP)

```python
@dataclass(frozen=True)
class RecoveryStrategy:
    name: str
    pre: Callable[[State, CEC], bool]
    post: Callable[[State], bool]
    cause_match: Callable[[CEC], float]   # ∈ [0,1]：策略与解释原因的匹配度
    residual_risk: Callable[[CEC], float] # ∈ [0,1]：该原因下策略的残余风险

STRATEGIES = {
    'tuck_roll': RecoveryStrategy(
        name='tuck_roll',
        pre=lambda x, e: x.height > 0.2 and x.head_clearance > 0.1,
        post=lambda x: x.orientation_err < 0.3,
        cause_match=lambda e: 0.9 if e.type == 'pushed' else 0.3,
        residual_risk=lambda e: 0.2 if e.type == 'slipped' else 0.1),
    'knee_up': RecoveryStrategy(
        name='knee_up',
        pre=lambda x, e: x.leg_reachability > 0.5 and x.support_area > 0.05,
        post=lambda x: x.height > 0.6,
        cause_match=lambda e: 0.85 if e.type == 'slipped' else 0.4,
        residual_risk=lambda e: 0.25 if e.type == 'pushed' else 0.15),
    'sit_to_stand': RecoveryStrategy(
        name='sit_to_stand',
        pre=lambda x, e: x.support_area > 0.10 and x.actuator_health > 0.6,
        post=lambda x: x.height > 0.6,
        cause_match=lambda e: 0.7 if e.type == 'actuator_fault' else 0.35,
        residual_risk=lambda e: 0.3 if e.type == 'terrain_collapse' else 0.1),
    'wall_assist': RecoveryStrategy(
        name='wall_assist',
        pre=lambda x, e: x.wall_within_reach,
        post=lambda x: x.height > 0.6,
        cause_match=lambda e: 0.6,
        residual_risk=lambda e: 0.05),
}

def select_recovery(x: State, cec: CEC, rvc: RVC,
                    value_ensemble: ValueEnsemble,
                    beta: float = 0.5, gamma: float = 0.3) -> RecoveryDecision:
    """CEC 条件化的恢复策略选择；无可恢复策略则请求人类/受控倒地。"""
    ranked = []
    for name, sigma in STRATEGIES.items():
        if not sigma.pre(x, cec):
            continue
        r = rvc.recoverability(x, name, value_ensemble)
        if not r.valid:
            continue
        score = r.rho + beta * sigma.cause_match(cec) - gamma * sigma.residual_risk(cec)
        ranked.append((score, name, r))
    if not ranked:
        return RecoveryDecision(action='controlled_fall_or_human', reason='no_viable_recovery')
    score, name, r = max(ranked, key=lambda z: z[0])
    return RecoveryDecision(action=name, rvc=r, cec=cec, score=score,
                            explanation=render_rationale(name, r, cec))
```

### IP-482 Explanation-Recovery Ledger & Trust Monitor (ERLTM)

```python
@dataclass
class ExplanationRecoveryLedger:
    """ERLTM：把 CEC 与恢复结果配对回写，监控解释漂移与信任校准。"""
    drift_window: int = 200
    min_verify_rate: float = 0.80
    min_cec_conf: float = 0.60

    def __post_init__(self):
        self.entries: list[LedgerEntry] = []
        self.cause_hist = defaultdict(list)

    def record(self, cec: CEC, decision: RecoveryDecision, outcome: RecoveryOutcome):
        consistent = self._check_consistency(cec, decision, outcome)
        self.entries.append(LedgerEntry(cec, decision, outcome, consistent))
        self.cause_hist[cec.type].append(cec.kappa)

    def _check_consistency(self, cec, decision, outcome) -> bool:
        # 解释若为真：按原因匹配选出的策略应更可能成功
        if outcome.success and cec.kappa < 0.3:
            return False          # 成功但解释很弱：可能是运气，标记待复核
        if (not outcome.success) and cec.kappa > 0.8 and decision.cause_matched:
            return False          # 高置信解释 + 匹配策略却失败：解释可能错误
        return True

    def health(self) -> dict:
        recent = self.entries[-self.drift_window:]
        verify_rate = np.mean([e.cec_verified for e in recent]) if recent else 1.0
        drift = self._distribution_shift(self.cause_hist)
        return {
            'verify_rate': verify_rate,
            'explanation_drift': drift,
            'need_human': (verify_rate < self.min_verify_rate) or (drift > self.drift_thresh),
        }
```

### IP-483 Recovery Rehearsal Simulator (RRS)

```python
def rehearse_and_falsify(cec_batch, simulator, n_rollout=256):
    """离线批量证伪：对每条 CEC，检查其反事实主张在扰动重采样下是否仍成立。"""
    report = []
    for cec in cec_batch:
        flips = 0
        for _ in range(n_rollout):
            w = simulator.sample_disturbance()
            tr = simulator.rollout(cec.fallen_state, do=cec.s_cf, disturbance=w)
            flips += int(not tr.fell)
        report.append(FalsificationReport(
            cec_id=cec.id, flip_rate=flips / n_rollout,
            sound=(flips / n_rollout) >= 1.0 - cec.eps))
    return report
```

### CIFR 统一执行流（在 CADVS 单步基础上扩展）

```python
def cifr_step(robot_state, sensor_data) -> ControlOutput:
    """正常路径完全复用 CADVS；仅 FEC 触发后进入解释-恢复分支。"""
    # 0) 正常证书链（与原 cadvs_step 一致）
    fec = FEC_NODE.update(robot_state, sensor_data.contact, sensor_data.t)

    if fec is None:
        return cadvs_step(robot_state, sensor_data)      # 正常分支：Exec 不变

    # 1) 跌倒分支：先算恢复可行性（RVC），解释与恢复并行争取时间预算
    t0 = now()
    rvc_results = RVC.certify(robot_state, cec=None, value_ensemble=VALUE)
    # 2) 解释有硬预算：超过 T_explain_budget 则降级为「解释延后」并采用保守恢复
    cec = EXPLAIN.explain(trajectory_buffer, fec,
                          deadline=t0 + T_explain_budget)
    explanation_deferred = cec is None or not cec.sufficient

    if explanation_deferred:
        # 保守：只用可恢复性排序，不依赖未完成的因果解释
        decision = select_recovery(robot_state, CEC.conservative(fec), RVC, VALUE,
                                   beta=0.0, gamma=0.5)
    else:
        decision = select_recovery(robot_state, cec, RVC, VALUE)

    # 3) 执行恢复，同时监控再跌倒（二次 FEC）
    out = RECOVERY_NODE.execute(decision)
    LEDGER.record(cec, decision, out.outcome)
    if out.refell:
        return cifr_step(out.state, out.sensors)          # 二次恢复，带新证据
    if LEDGER.health()['need_human']:
        out.flags.append('request_human_supervision')
    return out
```

## 3. 复杂度分析（增量）

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 | 实时性指标 |
|---|---|---|---|---|
| FEC 裕度+CUSUM | O(dim x) | O(1) | 1kHz | < 0.05ms |
| RVC 集成 LCB（每策略） | O(N_ens·T_rec/Δt) | O(N_ens·H) | N_ens=5, 5 策略 | 5–15ms |
| CEC 候选集搜索 | O(Σ_k C(n,k)·n_cf·H) | O(n_cf·H) | n≤12, k≤3, n_cf=64 | 20–200ms（可并行/提前终止） |
| CCRP 选择 | O(|Σ|) | O(|Σ|) | |Σ|≤5 | < 0.1ms |
| ERLTM 回写/漂移 | O(window) 摊还 | O(window) | window=200 | < 0.1ms |
| RRS 离线证伪 | O(N·n_rollout·H) | O(n_rollout·H) | N=批大小 | 离线 |

**关键时序约束**：恢复窗口 T_rec≈2.5s，但**首次恢复动作**通常要求在 150–400ms 内下发。因此 CEC 必须支持「随时中断」：先用前 k 层候选集给出可用解释，超预算即返回 `explanation_deferred`，绝不让解释计算阻塞恢复动作。这是本方案与「先解释后行动」的离线 XAI 范式的根本区别。

## 4. 正确性论证（增量）

### 引理 32（FEC 的检测延迟—误报权衡）

**陈述**：设跌倒后可行裕度每步平均下降 Δ > cusum_k，噪声方差 σ²。则单边 CUSUM 的期望检测延迟满足 E[δ_det] ≤ cusum_h/(Δ−cusum_k) + O(1)；无跌倒（H0）时误报的平均运行长度 ARL₀ ≳ exp(2·cusum_k·cusum_h/σ²)。

**证明要点**：CUSUM 统计量 g_k = max(0, g_{k−1} + (m₀−m_k) − cusum_k) 在跌倒后具有正漂移 Δ−cusum_k，首次越过 cusum_h 的期望时间由 Wald 恒等式给出上界；H0 下为负漂移随机游走，越界概率由 Chernoff 界控制，取指数率即得 ARL₀。∎

**工程含义**：`cusum_h` 是「早报/误报」旋钮；跌倒恢复宁可早报（误报的代价是多余的低幅保护动作），因此默认偏向低 `cusum_h`，再由 FEC 的 `margin_floor` 硬触发兜底。

### 引理 33（RVC 的可恢复性可靠性下界）

**陈述**：设真实恢复成功概率为 V_rec(x,σ)，集成估计 V̂ 满足 |V̂−V_rec| ≤ ε_v 以概率 ≥1−δ_est。若 ρ_rec(x)=LCB(V̂)−V_min>ε_v，则 V_rec(x,σ) > V_min，即以置信度 ≥1−δ_est 该策略的恢复成功概率超过可接受下界。

**证明**：由 LCB(V̂) ≤ V̂ 且 |V̂−V_rec|≤ε_v，有 V_rec ≥ V̂−ε_v ≥ LCB(V̂)−ε_v > V_min。∎

**诚实声明**：ε_v 无法被有限集成严格保证，只能由 RRS 的回放校准给出经验上界；分布外跌倒（未见过的接触/地形组合）会使 ε_v 增大，此时 ρ_rec 的证书效力下降——这正是本轮最大风险的量化入口。

### 引理 34（CEC 在模型误差下的近似可靠性）

**陈述**：设 SCM 的转移误差满足 ‖F_M − F_true‖_∞ ≤ ε_M，且跌倒事件 φ 对状态轨迹的依赖是 L-Lipschitz 的。若 CEC 在模型 M 下以邻域 ε_ball 验证 S 为充分原因，则在真实系统中，对 do(S=s′) 的反事实使 φ 翻转的概率 ≥ 1 − L·(ε_M + ε_ball)/(κ·δ_φ)，其中 δ_φ 为 φ 的判决裕度。

**证明要点**：模型与真实轨迹的偏差被 L(ε_M+ε_ball) 放大；只要该偏差小于 φ 的判决裕度 δ_φ，反事实的定性结论（跌倒/不跌倒）不变；对干预空间取测度并用 κ 归一即得翻转概率下界。∎

**工程含义**：CEC 的可靠性不是布尔值，而是随 ε_M 单调下降的连续量。ERLTM 用「解释-结果一致性」在线估计 ε_M 的有效值；一旦 verify_rate 跌破阈值，就降低对解释的信任并要求人类介入。

### 命题（解释-恢复一致性，条件性）

**陈述**：若 (i) CEC 是充分原因（引理 34 意义下可靠），(ii) 策略库对每个原因类别存在 cause_match 高的策略，(iii) 该策略的残余风险低于原因无关基线，则按 CCRP 的评分选择恢复策略的期望成功率不低于原因无关选择。

**说明**：这不是无条件定理——它依赖「原因匹配 ⇒ 恢复有效」这一经验假设。该假设本身必须由 RRS 与在线账本持续检验；命题的价值在于把「可解释性是否有用」转化为可证伪的统计假设，而非先验信念。

### 定理（CIFR 的执行集安全性）

**陈述**：在 FEC 未触发时，CIFR 的执行与 CADVS 完全一致，故 Exec_CIFR ∩ {m(x)≥0} = Exec_CADVS。在 FEC 触发后，恢复动作仅在满足 RVC(ρ_rec>0) 与 Pre(σ) 时被准入；因此恢复分支不会执行任何「既未被证明可恢复、也不满足物理前置条件」的动作。

**证明**：正常分支直接调用 `cadvs_step`，执行集相同。恢复分支中 `select_recovery` 只保留 `pre(x,cec) ∧ rvc.valid` 的策略，`rvc.valid ⇔ ρ_rec>0`；若集合为空则返回 `controlled_fall_or_human`，不产生未认证的主动动作。∎

**诚实声明**：该定理只保证「不执行未认证动作」，**不保证恢复一定成功**——ρ_rec 是估计值，分布外会失真。CIFR 的安全性来自「认证 + 降级 + 人类兜底」的组合，而非恢复本身的确定性。

## 5. 实验设计

### 5.1 平台与场景

- **仿真**：MuJoCo / Isaac Gym，双足（Cassie）与人形（Unitree H1）各一；扰动族 W = {推力脉冲、低摩擦地面、地形台阶塌陷、执行器饱和、负载突变}。
- **真机**：人形平台，安全吊架 + 软垫；先做受控跌倒（pull-release）再逐步放开。
- **跌倒注入**：按 6 类原因 × 3 个强度分层采样，训练/测试按**原因组合**划分，刻意留出未见过组合用于 OOD 评估。

### 5.2 基线与对照

| 基线 | 说明 |
|---|---|
| B0 无恢复 | 跌倒后急停（CADVS 现状） |
| B1 固定策略 | 始终用同一恢复动作（如 knee_up） |
| B2 无解释的 RL 恢复 | 可恢复性优先，不用 CEC |
| B3 事后解释 | 先恢复，再用 SHAP/梯度做事后归因（离线） |
| Ours CIFR | FEC+RVC+CEC+CCRP+ERLTM |

### 5.3 指标

- **恢复成功率**（T_rec 内回到 K_up 并稳定 ≥1s）；
- **再跌倒率**（恢复过程中二次 FEC）；
- **首次动作时延**（FEC→首个恢复指令）；
- **解释可验证率**（CEC 在 RRS 回放中通过的比例）；
- **解释稳定性**（同原因类别内解释集合的 Jaccard）；
- **解释延迟 / 超预算降级率**；
- **信任校准**（人机实验：操作员对「采纳/否决建议」的校准误差 Brier 分数）。

### 5.4 预期结果（待验证假设，非既成事实）

| 假设 | 预期 | 备注 |
|---|---|---|
| H1 | CIFR 恢复成功率比 B1 高 15–25%，比 B2 高 5–12% | 主收益来自原因条件化 |
| H2 | CEC 在分布内可验证率 > 90%，OOD 显著下降 | OOD 下降是本轮最大风险 |
| H3 | 首次动作时延 < 300ms（含解释提前终止） | 依赖并行与预算机制 |
| H4 | 解释-结果一致性高的样本，恢复成功率更高 | 检验「解释有用」命题 |
| H5 | ERLTM 的 need_human 信号能提前捕获 OOD 解释失效 | 用 AUROC 评估 |

### 5.5 消融

- 去掉 CEC（β=0）：测解释对恢复的边际贡献；
- 去掉 RVC（仅用 cause_match）：测可恢复性证书的必要性；
- 去掉 ERLTM 人类交接：测误解释被放行的代价；
- 调整 T_explain_budget：画「解释质量—恢复时延」帕累托曲线；
- 冻结 SCM 的某个变量（模拟模型盲区）：测 CEC 在模型误设下的退化。

## 6. 已知风险与缓解（增量）

| 编号 | 描述 | 严重度 | 缓解措施 | 剩余风险 |
|---|---|---|---|---|
| R33 | **解释的模型自指**：用漏报跌倒的同一模型解释跌倒，OOD 下高置信错误 | **极高** | 1) ERLTM 在线一致性回写 + 漂移检测；2) RRS 批量证伪；3) 多模型/多假设 CEC 集成，冲突时降级；4) 低 verify_rate 强制人类介入 | 真正的新原因（训练分布外）无法被现有变量集表达，解释会系统性遗漏 |
| R34 | **解释延迟与恢复窗口冲突** | 高 | 1) CEC 随时可中断 + 分层提前终止；2) 超预算即 `explanation_deferred`，用保守策略；3) ExplainNode 与 RecoveryNode 并行、独立线程 | 极端算力受限时解释几乎总是延后，退化为 B2 |
| R35 | **FEC 误报/迟报** | 高 | 1) CUSUM 阈值 + 硬裕度双门；2) 误报只触发低幅保护动作，不直接切换恢复；3) 迟报由 `margin_floor` 兜底 | 快速跌倒时物理裕度骤降，任何检测都有下界延迟 |
| R36 | **策略库覆盖不足** | 中 | 1) `controlled_fall_or_human` 作为显式兜底；2) RRS 覆盖度评估驱动策略扩充；3) 在线学习新策略但须先过 RVC | 新地形/新形态需要新策略，库扩充滞后 |
| R37 | **解释-动作的 Goodharting**：策略优化「解释好看」而非真恢复 | 高 | 1) 解释与恢复目标解耦（CEC 由独立 ExplainNode 生成）；2) 以恢复结果而非解释评分做最终奖励；3) 定期用 RRS 审计 | 若部署指标仍含「解释质量」，仍可能被间接优化 |
| R38 | **人类信任误校准**：过度信任或过度否决 | 中 | 1) 解释证书附置信度与验证率，而非单一结论；2) 人机实验做 Brier 校准；3) 明确标注 `explanation_deferred` | 操作员可能忽略置信度，只看结论 |

## 7. 本轮最大风险（最终确认）

**一句话**：**可解释跌倒恢复的模型自指陷阱**——恢复与解释共用同一个在跌倒瞬间已被证明不可靠的世界模型，分布外跌倒会让系统以高置信度签发一个自洽却错误的因果证书，并把恢复策略精确地引向错误动作；「被认证的错误理解」比沉默的失败更危险。
