# 第 11 轮（新灵感循环第 3 轮；本轮灵感：「ROS」×「伦理与合规」）
> **基线**：第 10 轮 MetricVoiceGauge-VEX（定义 540–547；引理 87–90；实验 E571–E590）。
> **本轮纪律**：**部署接地 + 可问责证据 + 双格退化**。ROS 治理 v10 的「纸面中间件」债：κ_m 只是抽象契约，没有落到 QoS、生命周期与执行器，超时/丢消息/时钟跳变的失效语义没有进入退化语法；伦理与合规治理 v10 的「解释≠问责」债：解释给人看，却没有第三方可重放的证据链、没有人类权威与同意的明确语义，也没有把规范失败设计成 fail-closed。关键转向：**性能退化用中立元，规范退化用义务闩锁**——两套格不可混用。

## 0. 直觉与动机

**灵感 1（ROS → 契约的物理落地）**
直觉：v9 的 ContractMiddleware 读起来像调度器，写起来像 if-else 的包装；它假设"超时会被抓住、消息不会旧、节点不会假活"。真实机器人上，这些假设由 DDS/QoS/executor/生命周期决定。ROS 2 恰好提供了把这些假设变成**可观测事件**的机制：deadline QoS 的 `requested_deadline_missed`、liveliness 的租约丢失、lifespan 的过期丢弃、lifecycle 的状态迁移、callback group 与 executor 的优先级。核心创新：**ROS 契约运行时（ROS Contract Runtime, RCR）**——把 κ_m 编译成 QoS 配置 + 生命周期 + 执行器优先级，让"超时即注入 v^⊥"从代码约定变成中间件事件；并用 MCAP/rosbag2 把输入与决策摘要落盘，支持审计重放。诚实边界：DDS 不是硬实时，QoS 只是"尽力而为的语义承诺"，所以必须用 E591–E593 实测，而不是声称证明。

**灵感 2（伦理与合规 → 可问责证据与失败闭合）**
直觉：v10 的 ECM/CAE 解决了"机器人能否解释"，却没解决"谁为这次解释负责、凭什么相信规则本身、出事后能否第三方复核"。合规章命不是给系统加一个"道德打分器"，而是三件事：(i) **证据**——每次决策都有可验证、可重放、可长期锚定的记录；(ii) **权威**——人类能及时否决/选择，但人类点头不能绕过安全证书；(iii) **闭合**——规范模块失效时必须更保守，而不是退回"无约束"。核心创新：**合规证据账本（Compliance Evidence Ledger, CEL）** + **合规权威闸门（Compliance Authority Gate, CAG，含规范编译器 NC 与人类权威令牌）**。最关键的伦理修订：v9 的 ID 会在线做 with/without 模块的消融实验——这是在部署系统上、可能在有人在场时做随机对照试验；改为**影子消融**：只对日志做反事实评估，绝不改变实际动作。

**统一直觉：两个正交的格**
性能模块坏了，用中立元补上，系统"少一个增强"；规范模块坏了，不能补"无约束"，只能收紧权限。前者是**能力格 P**，后者是**权限格 N**。v11 把退化写成二元组 `(p,n)`，`A_exec = A_perf(p) ∩ A_norm(n)`。这不是数学装饰：它解释了为什么"严格退回 v10"对性能模块成立，却对合规模块必须反过来——**规范没有中立元**（命题 2）：在权限格上，"无约束"是顶元素而不是恒等元；把顶元素当作失效补偿，等价于 fail-open。

## 1. 研究问题（轮次升级版）

- **Q7（契约的物理语义）**：如何把 κ_m 精化为 ROS 2 QoS/生命周期/执行器配置，使 deadline miss、liveliness 丢失、消息过期三类失效在**下游使用之前**确定性地变成 v^⊥？在非硬实时 DDS 上，哪些性质可以实测、哪些只能声明为假设？
- **Q8（合规的单向性与失败闭合）**：如何把规范编译为只做交集的约束，并保证"规范模块失效 ⇒ 权限单调不增"？当规范与安全内核冲突（规则要求禁止唯一的停车动作）时，系统应如何 fail-closed 而不静默丢规则？
- **Q9（可问责的边界）**：账本 + 人类令牌能提供何种可审计性？"人类在环"在 50Hz 闭环里如何避免退化为自动化偏见下的橡皮图章？影子消融能否在不做在线实验的前提下，保留足够的模块归因？

## 2. 设计原则（在 P13–P14 基础上新增 P15–P18）

**P15 ROS 契约落地律（ROS Contract Realization, RCR）**
每个 κ_m 必须绑定到可观测的中间件语义：`deadline ≤ D_m`、`lifespan ≤ D_m`、`liveliness_lease ≤ D_m`，安全通道 RELIABLE，控制命令必须带 lifespan（陈旧命令不得执行）。三类事件 `deadline_missed ∨ liveliness_lost ∨ stale` 在当周期注入 v_m^⊥。RCR 失效 ⇒ 退回 v10 的进程内 MW（语义等价、保证较弱），而不是让系统失去退化能力。

**P16 义务闩锁律 / 合规失败闭合（Fail-Closed Compliance, CEL/CAG）**
规范约束只做交集：`A_allowed = A_cert ∩ C_norm`。规范模块失效不得释放任何已生效义务；义务集 `O(t)` 单调不减（越积越多），解除必须由人类在**证据齐备**后显式重授权。账本不可写 ⇒ 禁止高风险动作（A3→A2/A1），而不是"先干后补日志"。规范与安全内核冲突 ⇒ 进 A0 并报配置错误，绝不静默丢弃规则。注意：这与性能模块的中立元退化**方向相反**，是刻意的。

**P17 人权不越证书律（Human Authority Cannot Bypass Certificate, CAG）**
人类权威可以**否决、选择、停机**，但不能把未认证的动作变成已认证：`A_human ⊆ A_cert ∩ C_norm ∪ {safe_stop}`。高风险动作需要绑定 `(plan_hash, scope, expiry, nonce)` 的签名同意令牌；硬件急停独立于软件，软件否决不能替代硬件急停。人类授权不是安全证明，只是权限选择。

**P18 影子实验律（Shadow Experimentation, ID 修订）**
禁止在部署系统上对会影响人类的行为做在线随机对照。模块贡献只能通过日志上的反事实/离策略评估估计；支撑不足时 `c_m = unknown ⇒ active`。影子消融不得改变任何执行动作（引理 95）。在线归因的目的从"删模块"改为"发现冗余"，伦理上从"对人做实验"改为"对日志做审计"。

## 3. 与基线的接口（如何退化）

v11 的退化不是一条链，而是**双格**（定义 554）：
- **能力格 P**（性能/功能，沿用中立元）：L0 全增强 → L1 无 RCR（退回 v10 MW）→ L2 无 v10 新模块（退回 v9）→ L3 无 AC（退回 v8 逐步）→ L4 无 MW（退回 v8 手写网关）→ L5 无 ID（全模块 active）→ L6 无 DA/SPR/Cal（退回 v7）→ L7 退回 v6。任一性能模块失效注入其 v^⊥，逐位等价上一版本。
- **权限格 N**（规范/权威，失败闭合）：A3 全自主 → A2 人在环监督（高风险需同意）→ A1 逐块同意/遥操作 → A0 安全停驻。规范模块失效、账本不可写、人类权威不可用、伦理包络越界，都只能把 n 往下推，**绝不上移**；恢复必须走显式释放协议（定义 554）。
- **组合**：`(p,n)` 的每次失效都按分量单调下降；`A_exec(p,n) = A_perf(p) ∩ A_norm(n)`。因此"性能上退回 v10"与"权限上收紧"可以同时发生，互不抵消。这也是 v11 对"严格退化链"的修订：**性能可回退，规范只能收紧**。

## 4. 预期贡献

1. **ROS 契约运行时**：把抽象退化链编译成 QoS/lifecycle/executor 的可观测事件，给出"三类中间件失效 ⇒ v^⊥"的精化引理，并用 MCAP 审计重放；
2. **双格退化与规范无中立元**：形式化"性能用中立元、规范用 fail-closed"的分野，证明规范失效只能收缩权限（引理 92–93、命题 2）；
3. **可问责证据链**：Merkle 化见证账本 + 外部锚定 + 可验证擦除，把"解释"升级为第三方可复核、且能兼顾隐私删除的证据；
4. **人类权威的工程语义**：同意令牌、硬件急停、防重放、以及"人类不能绕过证书"；用 E599–E600 直接测量自动化偏见；
5. **影子消融**：把 v9 的在线实验伦理问题改为离策略评估，安全中性且不做人体实验；
6. **E591–E610**：QoS 失效、审计重放、双格组合、失败闭合、令牌攻击、账本防篡改、隐私擦除、监管映射、影子归因、旁观者/弱势者伦理场景、端到端合规仿真。

## 5. 本轮最大风险

**一句话**：把"留痕 + 人类点头"误当成安全与正当性本身——账本能证明系统按规则行事，却不能证明规则正确；而 50Hz 闭环里的否决权极易在自动化偏见下退化为事后盖章，使双格退化在合规外衣下把一个真实的不安全系统包装成"可问责"。

# 第 11 轮产物 · 创新点清单 v11：**MetricVoiceGauge-ARC**（Auditable ROS Contracts，可审计 ROS 契约）

> 背景：第 10 轮 MetricVoiceGauge-VEX（定义 540–547；引理 87–90；实验 E571–E590）。
> 本轮灵感：「ROS」×「伦理与合规」
> **继承纪律**：MetricVoiceGauge 九不变式（CVC-闭环、SpatialCert、RT-CVC、FaultCert、PrimitiveGraph、严格退化链、OTL、GCT、ER）全部保留；v10 的 VEF/ECM/CAE、v9 的 AC/MW/ID、v8 的 DA-ML/SPR/Cal 原样继承。**修订一条纪律**：中立元退化只适用于**性能格 P**；**规范格 N** 采用失败闭合（fail-closed），因为"无约束"不是规范的中立元，而是权限授予（命题 2）。新组件失效时：性能方向逐位退回上一版本；规范方向只允许降低自主性 A3→A2→A1→A0，绝不上移。

## 1. 符号体系增量（定义 548–558）

| 符号 | 含义 |
|---|---|
| `B(κ_m)` | ROS 2 契约绑定：QoS + callback group + executor priority（定义 548） |
| `G` | 退化守护者：唯一有权发布 `(p,n)` 的 lifecycle 节点（定义 549） |
| `TCB` | 可信计算基：不可蒸馏、不可远程无签名升级的最小集（定义 550） |
| `C_norm(t)` | 规范编译器产出的约束集（定义 551） |
| `E_eth(s,ctx)` | 伦理包络：旁观者、弱势者、不可逆、隐私、非欺骗（定义 552） |
| `T_h` | 人类权威令牌：scope、plan_hash、expiry、nonce、签名（定义 553） |
| `(p,n) ∈ P×N` | 双格状态；`A_exec = A_perf(p) ∩ A_norm(n)`（定义 554） |
| `O(t)` | 义务闩锁集：`O(t) ⊆ O(t+1)`，只增不减；释放需证据+人签（定义 554） |
| `r_t, h_t, R_k, A_k` | 账本记录、链哈希、纪元 Merkle 根、外部锚定（定义 555） |
| `commit_t = HMAC_{k_t}(payload_t)` | 可验证擦除的键控承诺；擦除销毁 `k_t` 与 payload（定义 556） |
| `c_m^shadow` | 影子消融贡献估计；`unknown` 表示支撑不足、不得休眠（定义 557） |
| `D_{t0:t1}` | 决策转录：动作序列、中止点、K_eff、证书/权限结果（定义 558） |

**新增定义 548（ROS 2 契约绑定 ContractQoSBinding）** 对每个模块 m，绑定
```
B(κ_m) = (Reliability, Durability, History, Depth,
          Deadline D_qos, Lifespan L, Liveliness Liv, lease,
          CallbackGroup, ExecutorPriority)
```
并满足：`D_qos ≤ D_m`、`L ≤ D_m`、`lease ≤ D_m`；安全关键通道 `Reliability=RELIABLE`，高频感知可 `BEST_EFFORT` 但必须显式记账丢帧；数据依赖链上的模块放入互斥 callback group，只有无状态独立模块允许 reentrant；执行器优先级必须与 EDF 顺序一致，共享资源用优先级天花板或禁用阻塞锁。三类中间件事件在**下游使用之前**触发中立元注入：

| κ 字段 | ROS 2 机制 | 失效事件 | 注入 |
|---|---|---|---|
| `D_m` | Deadline QoS | `requested_deadline_missed` | `v_m^⊥` |
| `Ŵ_m` | WCET + `SCHED_FIFO` + `mlockall` | 运行超时/页错误 | `v_m^⊥` |
| 命令新鲜度 | Lifespan QoS | 样本过期被丢弃 | 视为 `stale ⇒ v_m^⊥` |
| 节点存活 | Liveliness（MANUAL_BY_TOPIC） | `liveliness_changed` 租约丢失 | `v_m^⊥` |
| 配置一致性 | Durability=TRANSIENT_LOCAL | 版本不匹配 | 拒绝进入契约（admission reject） |
| 蒸馏 | Lifecycle `activate/deactivate` | 状态迁移 | dormant ≡ `v_m^⊥` |

**新增定义 549（退化守护者 DegradationGuardian）** 单实例 lifecycle 节点 G，订阅 deadline/liveliness/stale/fault/账本/令牌事件，唯一有权发布 `/degradation/perf` 与 `/degradation/norm`。转移函数
```
T_G: (p, n, event) → (p', n')
```
满足失效转移 `p' ⪯ p`、`n' ⪯ n`；任何模块不能自报"我正常"来升层。P 的恢复需要健康检查与版本签名；N 的恢复必须走释范协议（定义 554）。G 由硬件看门狗监督，G 的双实例互斥，事件转移原子化并进账本。

**新增定义 550（可信计算基 TrustedCore, TCB）**
```
TCB = {M₀硬检查, SpatialCert, FaultCert, 安全停驻执行路径,
       G, 账本写前记录器, 规范安全内核检查器, 令牌验证器, 硬件急停接口}
```
TCB 模块 `φ^elig=false`，不可 dormant，不可被 ID 消融；不接受无签名远程升级；代码规模设上限（目标 ≤5k SLOC）并独立测试。设计命题是"TCB 之外的一切都可以坏，但坏法只能是更保守"，而不是"TCB 已被形式验证"。硬件急停不经过 ROS 消息路径，软件否决只是补充。

**新增定义 551（规范编译器 NormCompiler, NC）** 规则
```
r = (scope, predicate, actions, source, version, owner, justification)
C_norm(t) = ⋂_{r∈R(t)} { a : predicate_r(s_t, a, ctx) = true }
```
编译期四条义务（任一不满足 ⇒ ConfigError ⇒ A0 + 告警，绝不静默丢规则）：
1. **安全内核保持**：`K_safe ⊆ C_norm`，`K_safe` 至少含安全停驻与已认证避障动作；
2. **不反向**：规则不得否定硬安全谓词，不得"允许未认证动作"；
3. **可追溯**：每条规则必须有来源（法律/标准/机构政策）、版本、责任人、理由；
4. **确定性与时限**：运行期谓词必须确定性、可解释、单次评估 ≤0.1ms；学习模型只能离线提议规则，不能在运行期充当规范谓词。
若 `C_norm ∩ K_safe = ∅`，系统进 A0 并报配置错误；不允许"规则删不掉就忽略它"。

**新增定义 552（伦理包络 EthicalEnvelope, E_eth）** `E_eth(s,ctx)` 至少检查：
1. 非同意旁观者进入交互半径 ⇒ 自主性 ≤A2；
2. 检出弱势者（儿童/行动不便/认知障碍）⇒ ≤A2，且无监护人在场时 ≤A1；
3. 对人/未知物体的不可逆动作 ⇒ 需令牌，否则 ≤A1；
4. 超出声明目的的个人数据采集 ⇒ 拒绝采集（相机/麦克风门控），并记账；
5. 隐私区域/禁入区 ⇒ 不进入；
6. 非欺骗：语音与解释不得虚构确定性或拟人化误导，CAE 必须携带不确定度与反事实条件。
`A_norm(n) = C_norm(n) ∩ E_eth(n) ∩ A_human(n)`，三者的失败都只能收紧。

**新增定义 553（人类权威令牌 HumanAuthorityToken）** 令牌
```
T_h = (scope, plan_hash, rule_version, expiry, nonce, signer_id, sig)
```
用 SROS2/DDS Security 的密钥体系签名。`valid(T_h, plan, t) ⇔` scope 覆盖 plan、`plan_hash=H(plan)`、`t<expiry`、nonce 未用过、签名有效。高风险动作先验令牌后执行，令牌一次性；重放、过期、越 scope 一律拒绝并记账。急停/停机不要求令牌，任何人都可触发；但人类令牌**不能**授权 `A_cert ∩ C_norm` 之外的动作，尝试会被拒绝并记为 `authority_bypass_attempt`。

**新增定义 554（双格退化与义务闩锁 Two-Lattice Degradation）**
```
P = {P0 ≻ P1 ≻ … ≻ P7}        # 能力，中立元语义
N = {A0 ≺ A1 ≺ A2 ≺ A3}        # 权限，失败闭合语义
state = (p, n) ∈ P × N
A_exec(p,n) = A_perf(p) ∩ A_norm(n)
```
失效转移单调：`p' ⪯ p`、`n' ⪯ n`。义务集 `O(t)` 满足 `O(t) ⊆ O(t+1)`；`C_norm(t)=⋂_{o∈O(t)} C_o` 随义务增加而收缩。释放协议 `release(o)` 需要：修复/重标定证据 + 规范版本签名 + 人类签名 + 账本锚定；释放是唯一允许 n 上移的路径，且每次只允许上移一级。**P 的恢复**在健康检查通过后允许；**N 的恢复**不允许自动发生。产品序 `(p',n') ⪯ (p,n) ⇔ p'⪯p ∧ n'⪯n` 使 `A_exec` 对失效单调不增。

**新增定义 555（合规证据账本 ComplianceEvidenceLedger, CEL）** 每条记录
```
r_t = (t_steady, t_ros, plan_hash, cert_hash, evidence_root,
       Ψ_t, K_eff, module_states, p, n, decision, abort_point,
       human_token_id, human_action, rule_version,
       model_hash, calib_hash, config_hash, prev_hash)
h_t = H(r_t || h_{t-1})
R_k = MerkleRoot({h_t : t ∈ epoch k})
A_k = (R_k, t_k, sign_robot(R_k), timestamp_external(R_k))
```
账本由 `{r_t}` 与纪元锚 `{A_k}` 组成；外部锚可用 RFC 3161 时间戳或独立审计见证。写入协议是**写前意图 + 事后结果**两条记录；高风险动作必须先落意图并 fsync，再执行。若入队失败或持久化不可用 ⇒ `G` 立即降 N，禁止高风险动作；不允许"先执行、日志后补"。查询 API：`why_stop(plan_hash)`、`who_authorized(epoch)`、`which_rule(decision)`、`replay_span(t0,t1)`。

**新增定义 556（可验证擦除 VerifiedErasure）** 原始 payload 用每条记录独立的 HSM 密钥做键控承诺：
```
commit_t = HMAC_{k_t}(payload_t)
```
链上只存 `commit_t` 与元数据；payload 与 `k_t` 分库加密保存。擦除时销毁 `payload_t` 与 `k_t`，保留 `commit_t`，链仍可验证但内容不可恢复；`erase_event` 本身入账。保留策略分级：原始传感器 ≤24h、决策元数据 ≤30d、纪元根按监管要求长期保留。诚实边界：键控承诺防止低熵字典攻击，但擦除后无法再复核该条内容，审计只能证明"曾存在且未被改"，不能证明"当时判断正确"。

**新增定义 557（影子消融 ShadowAblation）** 设实际执行策略为 `π₀`，对 `φ^elig=true` 的模块 m，定义反事实策略 `π_{-m}`（把 m 输出置 `v^⊥`）。贡献
```
c_m^shadow = E_{s~d^{π₀}}[ J(π₀) − J(π_{-m}) ]
```
用日志上的离策略评估（IPS / 双重稳健）估计；**绝不**在物理系统上执行 `π_{-m}`，也不在线随机化安全相关行为。若有效样本量 `ESS < ESS_min` 或支撑条件不满足 ⇒ `c_m = unknown`，状态机保持不变（等价 active）。归因周期 `T_abl=500` 只表示"每 500 周期重估一次日志"，不再表示"做一次在线实验"；`H_off=3` 的 Schmitt 迟滞保留。

**新增定义 558（决策转录与审计重放 DecisionTranscript）**
```
D_{t0:t1} = [(t, plan_hash, action_id, abort_point, K_eff,
              cert_valid, permission_level, human_token_id)]
```
审计重放从 MCAP 输入 + 冻结配置 + 模型/标定哈希重建 `D'`。等价分两级：TCB 与确定性节点要求逐位/逐动作完全一致；ML 节点允许固定随机种子、确定性算子下的决策级等价（动作序列、中止点、权限级一致），时间戳容差 ε。若 `D'≠D` 且账本中无记录的非确定性来源，审计失败并告警。诚实边界：重放验证"规则一致性"，不验证物理世界真相，也不能补录未被传感器观测到的事件。

# IP-360 ROSContractRuntime：把 κ_m 落到 ROS 2 的可观测语义
class ROSContractRuntime:
    def bind(self, kappa):
        qos = QoSProfile(
            reliability=RELIABLE if kappa.safety else BEST_EFFORT,
            durability=TRANSIENT_LOCAL if kappa.config else VOLATILE,
            history=KEEP_LAST, depth=1,
            deadline=Duration(milliseconds=kappa.deadline_ms),
            lifespan=Duration(milliseconds=kappa.deadline_ms),
            liveliness=LivelinessPolicy.MANUAL_BY_TOPIC,
            liveliness_lease_duration=Duration(milliseconds=kappa.deadline_ms))
        return Binding(qos=qos,
                       group=MutuallyExclusiveCallbackGroup(),   # 数据依赖链
                       priority=kappa.priority)

    def run_cycle(self, runners, ctx, guardian):
        for m in sorted(self.bindings, key=lambda x: self.bindings[x].deadline):
            try:
                with deadline_guard(self.bindings[m].deadline):
                    ctx[m] = runners[m](ctx)
            except (DeadlineOverrun, StaleInput, LivelinessLost):
                ctx[m] = self.neutral[m]                 # 当周期注入 v^⊥
                guardian.report_failure(m)               # 只降不升
        return ctx

    def on_deadline_missed(self, m, t):
        self.inject_neutral(m, t); self.guardian.report_failure(m)

    def on_liveliness_lost(self, m, t):
        self.inject_neutral(m, t); self.guardian.report_failure(m)

# IP-362 ComplianceAuthorityGate：规范只做交集 + 人类权威 + 伦理包络
class ComplianceAuthorityGate:
    def __init__(self, nc, ethics, tokens, guardian, ledger):

        self.guardian, self.ledger = guardian, ledger
        self.level = "A3"

            return Decision.stop(reason="hard_stop")
        if not self.ledger.writable(ctx):
            self.guardian.downgrade_norm("ledger_unavailable")
            return Decision.stop(reason="no_witness")
        A_cert = plan.certified_actions()               # v10 证书给出的安全动作

        return Decision.execute(A_cert & A_norm)

## 4. 推导

**引理 91（QoS 精化的失效语义）** 若 `B(κ_m)` 满足定义 548 的约束，DDS 事件延迟有界，且执行器按优先级调度，则在每个控制周期内，模块 m 的 deadline miss、liveliness 丢失、消息过期都会在**下游读取之前**表现为 `v_m^⊥`；不会出现"使用陈旧值却认为模块正常"的路径。
证明：`Deadline QoS` 在 `D_qos` 到期时投递 miss 事件，`Lifespan` 在样本年龄超过 L 时丢弃，`Liveliness` 在 lease 到期时投递变化事件；三者均 ≤ D_m，故事件在契约周期内到达；`run_cycle` 先写 `ctx[m]` 再让下游读取，归纳得每周期要么拿到新值、要么拿到 `v^⊥`。∎
**诚实边界**：DDS/OS 不是硬实时；事件投递可能抖动，`SCHED_FIFO` 仍受中断、页错误、缓存影响。因此这是"语义精化 + 实测"的主张，不是硬实时证明；E591–E593 测事件时延与陈旧窗口。

**引理 92（单向合规的弱支配）** 假设 (A1) 安全内核 `K_safe` 在每次权限收紧后仍非空（至少含安全停驻）；(A2) v10 证书对 `A_cert` 可靠；(A3) 规范与人类只能做交集/选择，不能改写证书或动作参数。则对任意规则集和任意令牌（包括恶意令牌），`A_exec ⊆ A_cert`，最坏碰撞概率不高于 v10；规范失效只造成可用性下降。
证明：由定义 551/553/554，`A_norm ⊆ C_norm` 且 `A_human ⊆ A_cert ∩ C_norm`，故 `A_exec = A_cert ∩ A_norm ⊆ A_cert`；在保留 `K_safe` 的前提下，收缩动作集不会移除安全逃逸，最坏碰撞概率对动作集包含关系单调不增。∎
**诚实边界**：若某条规则移除了唯一的逃逸动作，安全性反而会下降；所以 `K_safe ⊆ C_norm` 是编译期硬约束，E598 专门 fuzz 这一点。

**引理 93（双格失效的单调性）** 在定义 554 下，任何失效事件都使 `(p,n)` 在乘积序上不增；P 的恢复需要健康证据，N 的恢复需要释放协议。故 `A_exec` 在失效序列上单调不增，规范失效不可能释放权限。
证明：`T_G` 的失效转移满足 `p'⪯p, n'⪯n`；`O(t)` 单调增长使 `C_norm` 单调收缩；`A_norm` 随 n 下降而收缩；交集对两个单调收缩的集合保持单调。恢复事件不在失效序列内，且 N 的恢复需显式 `release`，故不破坏失效序列的单调性。∎

**引理 94（账本防篡改与审计健全性）** 在抗碰撞哈希 H、不可伪造签名、外部锚定可用的假设下，修改任一已锚定纪元根会被以至少 `1−2^{-λ}` 的概率检出，除非攻击者取得签名密钥或与外部见证合谋。审计重放若产生 `D'≠D` 且账本无记录的非确定性来源，则判定审计失败。
证明：Merkle 根绑定纪元内全部 `h_t`；`h_t` 链式绑定前序记录；外部锚定把根固定到可信时间；签名绑定机器人身份。重放侧按定义 558 比较转录，差异即反例。∎
**诚实边界**：账本证明"记录未被改"，不证明"记录完整"（传感器盲区、未记录事件）、不证明"规则正确"、不证明"同意是知情的"；密钥泄露与见证合谋是明确失效模式。

**引理 95（影子消融的安全中性）** 影子消融是只读旁路，不存在从估计器到执行器的写路径；因此无论估计误差多大，执行动作序列与未启用影子消融时完全一致。若 ESS/支撑不足，`c_m=unknown⇒active`，不会静默休眠模块。
证明：由架构隔离（定义 557 与算法骨架），`ShadowAblation` 只读日志、只写 `c_m`；状态机仅在 `c_m` 已知且满足 Schmitt 阈值时迁移；`unknown` 不满足迁移条件。故执行路径不变。∎
**诚实边界**：离策略估计可能有偏，归因精度可能低于在线消融；这只影响效率，不影响安全，E605 量化偏差。

**命题 2（规范没有中立元）** 在权限格中，若 `v^⊥` 满足 `A ⊕ v^⊥ = A`，则 `v^⊥` 对权限是恒等元。但"无约束"对应权限顶元素 `⊤`，有 `A ∩ ⊤ = A`；把它用于失效补偿会保留全部权限，正是 fail-open。若要求失效时 `A ⊕ failure ⊆ A`，则 `v^⊥` 不能是 `⊤`，也就不再是"中立元"。故规范模块不能用中立元代数退化，必须用义务闩锁与权限下降。∎
（这正是 v11 修订"任一模块失效即注入中立元"的地方：该纪律只对性能格成立。）

**命题 3（可问责 ≠ 正当性）** 账本可以证明"系统按记录在案的规则、用记录在案的证据、做出了记录在案的决策"，但不能证明规则本身正当、证据充分、同意是知情的。故 CEL/HAG 是可问责性的必要条件，不是伦理正当性的充分条件；必须配合外部治理、第三方审计与"拒绝执行"的权利。∎
（这是工程姿态与制度边界，不是数学定理。）

## 9. 本轮最大风险

**一句话**：把"留痕 + 人类点头"误当成安全与正当性本身——账本能证明系统按规则行事，却不能证明规则正确；而 50Hz 闭环里的否决权极易在自动化偏见下退化为事后盖章，使双格退化在合规外衣下把一个真实的不安全系统包装成"可问责"。
