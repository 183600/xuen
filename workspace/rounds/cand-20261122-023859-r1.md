# 第 1 轮（UniBot 线 · 新灵感循环第 1 轮；本轮灵感：「手势识别」×「检索增强生成」）

> **基线继承**：UniBot-SAGE v1（定义 U1–U12、引理 L1–L7、实验 E601–E618、创新点 IP-01–IP-08）。本轮不推倒 v1，而是把 v1 的「任务 token + 抓握隐变量」升级为「交互手势索引 + 非参数示范记忆」；新增 IP-09–IP-13、U13–U24、L8–L13、E619–E636。合规纪律不变：单 checkpoint、单 API、不读评测侧私有信息、不做任务硬编码。
>
> **数据纪律**：官方 teaser 榜单（`gen_leaderboard.py` 生成、尚未正式发布）只作**结构参考**，不作调参依据；本轮新增的定量证据全部来自官方 HF 数据集 `unitreerobotics/unibot-v1-challenge-dataset` 的本地缓存（15 任务 / 88 episodes / 42,646 帧，含关节、EE 位姿、夹爪与 action 标签），脚本与结果在 `exp/gear_r2/`，可复现。

## 0. 一句话

把「手势识别」当作**检索的查询（query）**、把「检索增强生成」当作**非参数技能记忆（key–value store）**：先用一个软性交互手势后验把当前处境压成低维索引，再从官方示范库检索同手势的未来动作块，作为**带覆盖/一致性门控的残差先验**叠加到 VLA 基线上；检索不可信时严格退回参数策略。

## 1. 直觉：两个灵感各击中 v1 的哪根软肋

### 灵感 1 ·「手势识别」→ 技能不是任务标签，而是可观测的交互手势

**直觉**：人类操作时，"手势"（捏、握、钩、推、拧）是意图与接触方式的压缩表示。v1 把「技能」实现成 32 个任务 token，这等于假设"同一任务 = 同一技能"；但同一个 Plug In Ethernet 里包含 reach / grasp / align / insert 四种完全不同的技能，而同一个"捏取"又横跨多个任务。任务 token 太粗，阶段 token 是人工定义的、没有数据依据。

**第一性原理**：操作轨迹本质是**接触状态的转移序列**。一个手势可以被定义为一段"给定它就能显著降低未来动作不确定性"的时序模式。在 Dex1 单自由度、无触觉、无手指关节的接口下，手势**不可能**靠手指形状识别，只能靠三样东西联合推断：物体-夹爪的相对运动、夹爪开合的时序、EE 位姿/速度的变化。因此本轮的手势识别不是"识别人类的手"，而是**识别机器人自己正在执行的交互模式**，输出一个**软相位后验**（soft phase posterior），而不是硬标签。

**三个可执行推论**：
- **(a) 手势是天然的低维瓶颈**：它把高维视觉/本体观测压成 M 维离散后验，对外观、背景、位置不敏感，正好对上 5 类泛化场景。
- **(b) 手势是检索的天然 key**：它比任务名细、比原始观测稳，是"该去示范库里找哪一段"的索引。
- **(c) 手势后验的不确定性本身可作门控**：后验越平，说明当前处境越不像任何已知手势，此时应少信检索。

### 灵感 2 ·「检索增强生成」→ VLA 的参数记忆会平均掉长尾，示范库不会

**直觉**：RAG 在语言模型里解决的是"参数记不住的长尾知识"。把 169 小时、约 32k 条示范压进一个 VLA 的权重，**高频模式被记住，低频但关键的最后一环（插入、旋转、细粒度对齐）被平均掉**——这正好对应 teaser 榜与 RoboDojo 共同暴露的断点：大部分模型能推进大半程，却死在最后的对齐/插入/释放。检索是**非参数记忆**：它不压缩，它原样保留每一条范例。

**第一性原理**：参数策略估计的是条件均值 `E[a | o]`，在接触丰富、多模态的未来上，条件均值会落在"两个可行动作之间"的不可行区域（mode averaging）。检索估计的是**条件分布的局部样本**，天然保留多模态。代价是方差与覆盖：检索只在查询附近有样本时才可靠。

**三个可执行推论**：
- **(a) 检索补长尾**：在示范少、接触密的阶段，检索的收益应大于参数回归——本轮实测确实如此（见 §2）。
- **(b) 检索天然可审计**：每个动作都能追溯到具体的示范帧 ID，直接服务官方"动作统计规律性/可信度"口径。
- **(c) 检索会"自信地错"**：分布外查询也会返回最近邻，且距离可能并不大。所以检索必须带**覆盖检测**，否则会把 OOD 场景带偏。

### 合成：手势是 query，示范是 key–value，覆盖是门

v1 的三层栈（接地/技能/适应/工程）保留，但技能层与接地层被重新接线：
- **接地层**：抓握隐变量之外，增加"交互手势后验"这一路软证据；
- **技能层**：IP-01 的任务 token 升级为**数据驱动的手势 token**（任务 token 仍保留作粗路由）；
- **适应层**：检索本身就是一种**推理期适配**——不更新权重，只换"参考范例"；
- **工程层**：检索有严格延迟预算与回退，必须能在 chunk 边界摊销。

一句话：**v1 用"学会的参数"做技能，GEAR 用"记得的范例"补技能的缺口**。两者不是替代，是残差关系。

## 2. 为什么是现在：官方真机示范数据上的三组证据

本轮没有只停在思辨。我们从官方 32 数据集缓存中取出 15 个任务、88 个 episode、42,646 帧（关节 14 维 + 左右 EE 位姿 12 维 + 夹爪 2 维，action 同构），构造"当前状态+速度 → 10 帧后的动作增量"的离线检索任务，比较参数回归（ridge）与检索（kNN，K=12，距离核加权），结果如下（`exp/gear_r2/subset.py`、`variants.py`、`retrieval_exp.py`）：

| 观测 | 数值 | 对设计的含义 |
|---|---|---|
| 分布内：检索 vs 参数回归 R² | **0.351 vs 0.209** | 同分布下检索显著优于线性参数基线 |
| 最难任务子集（PlugInEthernet/Unlock/DisconnectEthernet） | **0.411 vs 0.276** | 越接触密、越难，检索优势越大 |
| 接触阶段子集（夹爪闭合 <1.5） | **0.315 vs 0.178** | 断点处正是检索该发力处 |
| 单任务 PlugInEthernet | **0.699 vs 0.308** | 长尾接触技能被参数模型严重平均，检索保留范例 |
| 检索方差 → 实际误差（Spearman） | **0.731（接触阶段 0.765）** | 检索一致性是**可用的不确定性信号**，可做门控 |
| 硬手势过滤 / 软手势加权 / 纯检索 R²（同划分） | **0.267 / 0.275 / 0.330** | **硬过滤反而伤**：手势不能用来缩小检索库，只能软加权 |
| 留出任务 OOD：检索 vs 参数回归 R² | **0.021 vs 0.182** | 检索在 OOD 上**崩塌**，必须覆盖门控+参数回退 |
| 单任务 OrganizeBookshelf | **−0.064 vs 0.269** | 检索并非处处更好；收益需**按覆盖度预测** |

**克制解读**：这些数字不能证明"真机一定涨点"，但它们给出三个强约束：**(i)** 检索的收益是**任务/阶段异质**的，不是普遍增益，所以必须门控；**(ii)** 检索的失败模式是**覆盖不足**（OOD 崩塌），而不是"检索本身没用"；**(iii)** 手势若当作硬过滤会降低有效样本量，反而损害动作预测——这直接否定了"先分类手势、再只在同类里检索"的朴素组合，要求手势以**软先验**进入。

## 3. 研究问题（本轮新增 Q6–Q10）

- **Q6（手势词表怎么学才不是拍脑袋）**：能否用一个信息论目标（在"压缩观测"与"预测未来动作"之间取平衡）自动学出 M 个手势，使手势标签对未见物体/背景稳定，且比任务 token 更能预测未来动作？
- **Q7（检索如何不自信地错）**：如何用 k 近邻距离、检索后验方差、以及"最近邻是否同手势/同任务"构造一个**校准的覆盖分**，使 OOD 查询能被可靠识别并回退？
- **Q8（软手势如何进入检索）**：硬过滤已被实测否定；正确的软加权形式是什么？权重放在距离上、还是放在残差上？手势后验与检索相似度如何联合校准？
- **Q9（检索残差如何安全叠加）**：把检索结果当残差 `a = a_base + λ(a_ret − a_base)` 时，λ 如何由覆盖/一致性给出，才能保证"最坏退回基线"而不引入抖动与越界？
- **Q10（工程语义）**：检索应在每步做还是每 chunk 做？如何在 105 ms p99 预算内完成 ANN 检索 + 手势推断，并与 v1 的 chunk 缝合、多端口隔离共存？

## 4. 设计原则（新增 P7–P10）

- **P7 手势是软索引，不是硬分区**：手势后验只能以低权重进入检索与门控；禁止用 argmax 手势裁剪候选集（本轮实测硬过滤 −24% R²）。
- **P8 非参数记忆须带覆盖证书**：任何检索结果必须同时输出覆盖分与一致性分；覆盖不足时**禁止**让检索主导动作，只能退回参数策略。
- **P9 检索只做残差，不做主控**：检索不直接输出动作，只输出相对基线的残差先验，且残差受 trust-region 约束；λ=0 严格等于 v1。
- **P10 可追溯即合规**：每个动作记录检索到的示范 ID、距离、手势后验、门控值与延迟；这既是可信度证据，也是失败归因工具。

## 5. MVP 与退化链

**MVP = IP-09（手势词表）+ IP-10（示范检索库）+ IP-11（覆盖门控残差）+ v1 的 IP-02/IP-03 + 通用 VLA 基线**。
理由：IP-09/IP-10 决定检索的"键"和"值"是否成立；IP-11 是唯一能让检索**安全**落地的组件；三者都不依赖新数据，只依赖官方示范。

**严格退化链（任一环节不可用 ⇒ 行为回退，不漂移）**：
- **D0** 完整 GEAR（软手势 + 覆盖门控检索残差）；
- **D1** 检索不可用（覆盖低/延迟超预算）⇒ 退回**纯参数基线**（λ=0）；
- **D2** 手势后验不可用 ⇒ 用均匀后验（等于去掉手势软加权）；
- **D3** 覆盖/一致性估计不可用 ⇒ 禁止检索，只保留 v1；
- **D4** ANN 索引不可用 ⇒ 退化为小库精确检索或直接 v1；
- **D5** 整条新链路失效 ⇒ 永远保留一份能跑通、可信度合规的 v1 最小提交。

## 6. 预期贡献（可验收）

1. **把手势从"人工阶段标签"变成"数据驱动的软索引"**：给出信息论词表学习目标、软后验实现与跨任务稳定性指标。
2. **给出"非参数技能记忆"的可量化收益与边界**：在官方真机示范上测出检索相对参数回归的 R² 增益（分布内 +0.14、难任务 +0.14、PlugInEthernet +0.39），并诚实标出其 OOD 崩塌（0.02 vs 0.18）。
3. **覆盖门控的检索残差**：把"检索会自信地错"变成可检测、可回退的工程属性；给出校准曲线与最坏退化保证。
4. **否定朴素组合，给出正确组合**：用实验证明"手势硬过滤 + 同类检索"有害，提出"软手势加权 + 覆盖门控 + 残差叠加"的正确形态。
5. **可审计的检索动作**：每个动作可追溯到示范帧 ID，直接对齐官方可信度口径，并作为失败归因（reach/grasp/align/insert）的新证据源。

## 7. 本轮最大风险（一句话）

**最大风险**：检索库与基线策略同源于官方示范，检索的增益可能只是对训练分布的**记忆**；一旦进入 5 类泛化场景（未见物体/背景/位置），覆盖分会把检索关掉——于是它在基线已经不错的地方帮忙，在真正需要它的地方缺席，而少数"距离不远但语义错误"的检索还会把最后一环的对齐带偏。

## 8. 下一轮迭代计划（深化与修剪，不推倒重来）

- **深化**：把 IP-09 的软手势后验升级为**带时序的手势状态机**（与 v1 的抓握状态机共享隐状态）；把 IP-11 的门控从启发式升级为**保形预测（conformal）**，给出有限样本的"检索不劣于基线"覆盖率保证；把 IP-10 的检索从帧级升级为**相位对齐的 chunk 级**（DTW/时间规整），减少"动作相位错位"导致的假近邻。
- **修剪预案**：若 E621 显示覆盖门控无法把 OOD 检索的伤害压到基线以下（即门控后的成功率 < 纯基线），则**砍掉检索主线**，只保留"手势词表 + 检索式诊断"作为分析与归因工具；若 E625 显示 ANN 检索 p99 超预算，则把检索降为"每 episode 只查一次"的粗先验或直接停用。
- **保留项**：IP-09 的手势软后验、IP-11 的覆盖/一致性门控、IP-13 的检索审计在任何情况下保留（它们不依赖检索一定涨点，机制正确性最强，且能反哺 v1 的 IP-02/IP-06）。

# 第 1 轮产物 · UniBot-GEAR：手势软索引 × 非参数示范记忆 × 覆盖门控残差

> **GEAR = Gesture-Embedded Action Retrieval**（手势嵌入的动作检索）。
> **基线继承**：UniBot-SAGE v1（U1–U12、L1–L7、E601–E618、IP-01–IP-08）。本轮新增 IP-09–IP-13、U13–U24、L8–L13、E619–E636。v1 的 IP-01（SkillToken-MoE）、IP-02（GraspVerify）、IP-03（ChunkStitch）、IP-06（SimBench）全部保留；本轮把 IP-01 的任务 token 升级为「任务 token × 手势 token」双条件，把 IP-02 的抓握不确定性扩为「视觉/夹爪 + 检索一致性」双来源，并把 IP-06 的六因子分解扩一维「检索可覆盖性」。
> **数据纪律**：teaser 榜（`generated_from: gen_leaderboard.py`）只作结构参考；本轮定量证据来自官方 HF 数据集 `unitreerobotics/unibot-v1-challenge-dataset` 的本地缓存（15 任务 / 88 episodes / 42,646 帧），脚本 `exp/gear_r2/{loader,retrieval_exp,variants,subset}.py`，结果 `exp/gear_r2/{results,variants_id,subset}.json`。

## 0. 本轮结论摘要

**一句话路线**：把「手势识别」做成**软性交互手势后验**（query），把「检索增强生成」做成**带覆盖/一致性门控的示范残差**（key–value），输出 `a = a_base + λ·(a_ret − a_base)`；λ=0 严格等于 v1。

**五条量化依据**（官方真机示范，离线检索任务：状态+速度 → 10 帧后动作增量，K=12）：

| 证据 | 数值 | 推出的设计 |
|---|---|---|
| 分布内检索 vs 参数回归 R² | **0.351 vs 0.209** | 检索有真实增益，值得做 |
| 难任务子集 / 接触子集 | **0.411/0.276**、**0.315/0.178** | 火力在接触密集的最后一环 |
| 检索方差 → 误差 Spearman | **0.731**（接触 0.765） | 方差可做门控信号 |
| 硬手势过滤 / 软加权 / 纯检索（同划分） | **0.267 / 0.275 / 0.330** | 手势只能软加权，不能硬过滤 |
| 留出任务 OOD 检索 vs 回归 | **0.021 vs 0.182** | 必须覆盖门控 + 参数回退 |

**合规红线（继承 P5）**：单 checkpoint、单 `get_action` API；检索库只由官方示范离线构建；手势由观测推断，不由任务名硬编码；所有新模块都有 λ=0 的严格退化形态。

## 2. 创新点详述

### IP-09 · GestureLexicon（GL）软手势词表（P0）

- **动机**：v1 的 32 个任务 token 太粗（一任务含多技能），人工阶段 token 无数据依据；需要一个**数据驱动、可观测、对外观/位置不敏感**的中间表示。
- **与 v1 的差异**：v1 用任务 token 选专家；GL 用**手势后验**做更细的条件化，并把手势 token 同时作为检索 key。任务 token 保留作粗路由，二者相乘（任务 × 手势）。
- **技术可行性**：高。手势标签无需人工：用夹爪开合、EE 相对物体运动、关节速度的时序窗口做自监督聚类/时序对比学习；用信息论目标选 M，而非拍脑袋。
- **所需资源**：数据 = 官方 32 数据集；算力 = 单卡数小时（轻量 TCN/Transformer，<10M 参数）；接口 = 纯内部。
- **落地步骤**：①提取窗口特征（EE 相对位姿、夹爪开合及其差分、关节速度）；②按时序对比/掩码预测预训练编码器；③用 U15 的 IB/MDL 目标选 M 与离散化；④温度校准输出软后验；⑤跨任务/跨物体稳定性抽检。
- **风险**：①手势与任务高度共线 ⇒ 退化为任务 token（用互信息增量检验）；②M 选太大 ⇒ 每类样本不足（MDL 惩罚 + 最小类样本约束）；③未见物体上手势漂移 ⇒ 软后验 + 低置信不参与检索。

### IP-10 · DemoRetrievalBank（DRB）示范检索库（P0）

- **动机**：VLA 参数记忆会平均掉长尾接触技能；示范库是非参数记忆，原样保留范例。
- **与 v1 的差异**：v1 只用示范做训练；DRB 把示范同时作为**推理期可查的记忆**，且库是离线、只读、可审计的。
- **技术可行性**：高。key = 标准化后的状态+速度+手势后验（约 32–64 维）；value = 未来 H 帧动作块（残差空间）；ANN 用 HNSW/IVF-PQ；库大小 10⁶ 级、内存可控。
- **所需资源**：数据 = 官方示范（不新增）；算力 = 离线建库 + 在线 ANN；接口 = 无。
- **落地步骤**：①定义 key/value 与归一化（按任务或全局稳健标准化）；②去重/降采样控制库规模；③建 ANN 索引并标定查询延迟；④实现 top-K 返回（含距离与来源 ID）；⑤按任务/阶段统计覆盖。
- **风险**：①库偏向高频任务 ⇒ 长尾覆盖差（分层采样 + 覆盖报告）；②key 归一化不当 ⇒ 跨任务不可比（用相对量/分位数归一）；③示范噪声/失败示范入库 ⇒ 只保留成功 episode 或按回报加权。

### IP-11 · CoverageGatedResidual（CGR）覆盖门控残差（P0）

- **动机**：本轮实测检索在 OOD 上 R² 从 0.35 崩到 0.02，而参数回归仍有 0.18；不门控的检索会"自信地错"。
- **与 v1 的差异**：v1 的抓握介入是"高精度低召回"；CGR 把同一哲学用到检索：**只在覆盖足、邻居一致时才让检索说话**。
- **技术可行性**：高。覆盖分 = 第 k 近邻距离（按任务校准）；一致性分 = 检索后验加权方差 + 权重熵；λ 为二者的单调函数，并受 trust-region 约束。
- **所需资源**：算力 = 极小（<1 ms）；数据 = 官方示范 + 少量真机标定；接口 = 无。
- **落地步骤**：①在训练集上拟合覆盖分/一致性分的分布；②用保形预测（conformal）标定"检索不劣于基线"的阈值；③实现 λ 与残差叠加；④真机 A/B（E629）；⑤导出可靠性图。
- **风险**：①覆盖分对未见物体误判为"有覆盖" ⇒ 用多信号（距离+手势熵+邻居任务纯度）；②λ 抖动导致动作不连续 ⇒ λ 低通 + chunk 内冻结；③残差越界 ⇒ trust-region + 限幅。

### IP-12 · PhaseAlignedRetrieval（PAR）相位对齐 chunk 检索（P1）

- **动机**：帧级最近邻会匹配到"位置相近但相位不同"的窗口（如都在桌边，但一个在接近、一个在插入），造成假近邻；且每步检索浪费预算。
- **与 v1 的差异**：v1 的 IP-03 在 chunk 边界缝合动作；PAR 在 chunk 边界**检索**，并用 DTW/时间规整对齐检索到的未来块与当前相位，再交给 IP-03 缝合。
- **技术可行性**：中–高。DTW 在 H≤16 的短块上很便宜；相位可由手势后验给出。
- **所需资源**：算力 = 小；接口 = 无；数据 = 官方示范。
- **落地步骤**：①在 chunk 边界触发检索；②对候选未来块做 DTW/相位对齐；③在块内复用检索结果；④与 IP-03 缝合器联合调参；⑤消融帧级 vs chunk 级。
- **风险**：①对齐错位 ⇒ 用相位后验与 DTW 代价双门控；②chunk 过长 ⇒ 相位漂移（限制 C 与最大驻留）；③延迟峰值 ⇒ 预算内降 K。

### IP-13 · RetrievalAudit（RA）检索审计与回退（P1）

- **动机**：官方会看动作统计规律性与延迟波动；检索引入外部记忆，更需要可追溯，否则可信度受损。
- **与 v1 的差异**：v1 的 IP-08 记录延迟/jerk；RA 额外记录**检索决策链**：查询 key、覆盖分、一致性分、λ、返回的示范 ID 与距离、是否降级。
- **技术可行性**：高（工程）。
- **所需资源**：极小。
- **落地步骤**：①埋点；②导出 per-episode 检索报告；③异常检索（高 λ 低覆盖）告警；④一键停用检索并回放同一 episode；⑤N 端口并发隔离自检。
- **风险**：日志过大 ⇒ 采样 + 摘要；日志本身拖慢 ⇒ 异步写。

## 3. 符号与定义（U13–U24）

| 符号 | 含义 |
|---|---|
| `g_t` | 交互手势隐变量 ∈ {1..M} |
| `q_t(m)` | 手势后验 `P(g_t=m | o_{t−τ:t})` |
| `B` | 示范检索库 `{(k_j, y_j, m_j)}` |
| `c(q)` | 覆盖分（越小覆盖越好） |
| `u(q)` | 检索一致性分（越小越一致） |
| `p(a|q)` | 检索后验（未来动作块的混合） |
| `λ(q)` | 门控系数 ∈ [0,1] |
| `r(q)` | 检索残差 `â_ret − a_base` |
| `C` | chunk 级检索周期 |
| `ρ` | 残差 trust-region 半径 |

**定义 U13（交互手势）**：手势是轨迹的一个隐分割变量 `g_t ∈ {1..M}`，其取值使「给定手势后，未来 H 步动作的条件熵」最小、且「手势对观测的依赖」受约束（见 U15）。手势不是任务标签，也不是人工阶段。

**定义 U14（手势后验）**：`q_t(m) = softmax_m f_ψ(o_{t−τ:t})`，`f_ψ` 为轻量时序编码器（TCN/Transformer），输入为 EE 相对位姿、夹爪开合及差分、关节速度；输出经温度 `T_g` 校准。

**定义 U15（手势词表目标）**：`max_{q,ψ} I(g; a_{t+1:t+H}) − γ·I(o_{t−τ:t}; g)`，`M` 由 MDL/BIC 选择；等价于信息瓶颈的离散形式。其变分下界用 `E[log p_θ(a|g)] − γ·KL(q(o)‖p(g))` 优化。该目标保证手势是"为预测未来动作而存在"的压缩，而非任意聚类。

**定义 U16（示范检索库）**：`B = {(k_j, y_j, m_j)}_{j=1..N}`，`k_j = φ(o_{t−τ:t})`（标准化 key），`y_j = a_{t+1:t+H} − a_t`（动作增量），`m_j = q_j`（示范窗口的手势后验）。库只由官方成功示范离线构建，只读。

**定义 U17（覆盖分）**：`c(q) = d_(k)(q)`（查询到第 k 近邻的距离），按任务/阶段做分位数校准：`c̃ = (c − μ_c)/σ_c`；覆盖不足判据 `c̃ > τ_c`。

**定义 U18（检索后验）**：`p(a|q) = Σ_j w_j N(a; y_j, Σ_j)`，`w_j ∝ exp(−d_j/τ_d)·exp(α·log q_t(m_j))`，`α ≥ 0` 为**软**手势权重；`α=0` 退化为纯检索；禁止 `α=∞`（硬过滤）。

**定义 U19（一致性分）**：`u(q) = Σ_j w_j ‖y_j − ȳ‖² + H(w)`，`ȳ = Σ_j w_j y_j`，`H(w)` 为权重熵；`u` 越小说明邻居越一致。

**定义 U20（门控残差策略）**：`a = a_base + λ(q)·(â_ret − a_base)`，`â_ret = Σ_j w_j y_j`，`λ(q) = clip(σ((τ_c − c̃)/s_c)·σ((τ_u − u)/s_u), 0, 1)`，并施加 `λ‖r‖ ≤ ρ`；`λ=0` 严格等于 v1。

**定义 U21（软手势权重，替代硬过滤）**：`w_j ∝ exp(−d_j/τ_d)·q_t(m_j)^α`。硬过滤是 `α→∞` 的极限；引理 L10 说明该极限在覆盖不足时有害。

**定义 U22（chunk 级检索调度）**：仅在 `t ≡ 0 (mod C)` 触发检索，块内复用；`C` 与 `action_chunk_size` 对齐，且受最大驻留约束。

**定义 U23（参数回退）**：当 `λ < λ_min` 时，`a = a_base`；可选地，用同一库训练一个 ridge/flow 代理 `f_par`，在低覆盖时 `a = a_base + λ(f_par − a_base)`，保证 OOD 仍有非零先验。

**定义 U24（审计记录）**：每 chunk 记录 `(q_t, c̃, u, λ, {j, d_j}, latency, degraded)`；`degraded=1` 表示本次退回基线。

## 4. 关键算法骨架

```python
# ===== IP-09：软手势词表（离线训练，在线只跑编码器）=====
class GestureLexicon:
    def __init__(self, enc, M, T_g=1.0): self.enc, self.M, self.T_g = enc, M, T_g
    def posterior(self, obs_window):
        logits = self.enc(obs_window)            # EE 相对位姿 + 夹爪差分 + 关节速度
        return softmax(logits / self.T_g)        # q_t(m), 软后验

# ===== IP-10：示范检索库（离线建，只读）=====
class DemoRetrievalBank:
    def __init__(self, keys, values, gestures, index):
        self.k, self.y, self.m, self.index = keys, values, gestures, index
    def query(self, key, K=12):
        d, idx = self.index.search(key, K)       # HNSW / IVF-PQ
        return d, idx                            # 距离 + 示范 ID（可审计）

# ===== IP-11/12：覆盖门控残差 + chunk 级调度 =====
class GEARPolicy:                                # 暴露 metadata / get_action / reset
    def __init__(self, base, gl, bank, C=8, K=12, tau_c=2.0, tau_u=0.05, rho=0.2):
        self.base, self.gl, self.bank = base, gl, bank
        self.C, self.K, self.tau_c, self.tau_u, self.rho = C, K, tau_c, tau_u, rho
        self.sessions = {}

    def reset(self, port=None):
        self.sessions.setdefault(port, Session()).reset()

    def get_action(self, obs, port=None):
        s = self.sessions[port]
        q = self.gl.posterior(obs)                       # U14
        a_base = self.base.act(obs)                      # v1 策略
        if s.t % self.C != 0 or not s.retrieval_ok:       # U22：块内复用/不可用即回退
            s.t += 1; return a_base
        key = phi(obs)                                   # U16
        d, idx = self.bank.query(key, self.K)            # IP-10
        c = calibrate_coverage(d[-1], obs.task_hint)     # U17
        w = softmax(-d / tau_d) * (q[self.bank.m[idx]] ** alpha)   # U21 软手势
        ybar = (w[:, None] * self.bank.y[idx]).sum(0)    # U18
        u = (w[:, None] * (self.bank.y[idx] - ybar) ** 2).sum() + entropy(w)   # U19
        lam = gate(c, u, self.tau_c, self.tau_u)         # U20
        r = ybar - a_base
        lam = min(lam, self.rho / (norm(r) + 1e-6))      # trust-region
        a = a_base + lam * r
        s.audit(q, c, u, lam, idx, d)                    # U24 / IP-13
        s.t += 1
        return a
```

```python
# ===== 覆盖门控 + 保形校准（IP-11 步骤②）=====
def fit_conformal(base_err, ret_err, scores, alpha=0.1):
    """在验证集上求阈值：使 '检索误差 ≤ 基线误差' 的覆盖率 ≥ 1-alpha。"""
    gain = base_err - ret_err                       # >0 表示检索更好
    order = np.argsort(scores)                      # scores 越小越可信
    n = len(gain); k = int(np.ceil((n + 1) * (1 - alpha)))
    # 选择最大阈值，使被接受样本中 gain>0 的比例达到目标
    for thr in np.sort(scores)[::-1]:
        acc = scores <= thr
        if acc.sum() and (gain[acc] > 0).mean() >= 1 - alpha:
            return thr
    return -np.inf
```

## 5. 推导（引理 L8–L13）

**引理 L8（检索误差–覆盖界）** 设条件均值 `m(x)=E[Y|X=x]` 为 L-Lipschitz，噪声方差 `σ²`，kNN 回归在查询 `x` 处的期望平方误差满足 `E‖Y−ĝ‖² ≤ 2σ²(1+1/k) + 2(L·d_k(x))²`。因此检索相对基线 `f` 的增益只在 `E‖Y−f(X)‖²` 超过该界时为正；当查询远离库支撑（`d_k` 大）时界退化，检索必然崩。本轮 OOD 实测（0.021 vs 0.182）正是此界的经验体现。∎

**引理 L9（门控的最坏退化保证）** 若 `λ(q)∈[0,1]` 且施加 `λ‖r‖≤ρ`，则 `‖a−a_base‖ ≤ min(‖r‖, ρ)`；当 `λ=0` 时 `a≡a_base`。若 λ 是校准风险分 `u` 的单调不增函数，则由保形校准可得：被检索干预的样本中"检索误差大于基线误差"的比例以 `1−α` 概率不超过 `α`。⇒ 检索不会在统计上系统性劣于基线。∎

**引理 L10（硬手势过滤的方差惩罚）** 硬过滤把有效样本量从 `N` 降到 `N_m`，检索方差项约从 `σ²(1+1/k)` 增至 `σ²(1+1/k_m)`，且当手势后验不确定（误分类）时会移除本可降低偏差的邻居。故硬过滤只在"手势划分消除的偏差 > 有效样本量下降带来的方差惩罚"时有益。本轮实测硬过滤使同划分 R² 从 0.330 降到 0.267，说明该条件在粗手势下不成立。∎

**引理 L11（检索方差是误差代理）** 对混合后验 `p(a|q)=Σ_j w_j N(a;y_j,Σ_j)`，其协方差为 `Cov = Σ_j w_j(y_j−ȳ)(y_j−ȳ)^T + Σ_j w_j Σ_j`。若真实 `a` 服从同一混合，则 `E‖a−ȳ‖² = tr(Cov)`。故按 `u(q)` 排序即按期望误差排序；用保形分位数可把该排序转成有限样本覆盖保证。本轮实测 Spearman 0.731 支持该代理有效。∎

**引理 L12（延迟摊销）** 每步检索代价 `O(N_bank·d)`；chunk 级每 `C` 步检索一次 ⇒ 均摊 `O(N_bank·d/C)`；用 HNSW 近似检索为 `O(log N_bank)`。取 `N_bank≈10⁶, d=32, C=8`，检索均摊远低于 105 ms 预算；峰值由 `K` 与索引参数控制。∎

**引理 L13（覆盖分的 OOD 一致性）** 在密度有界且支撑偏移使局部密度下降的假设下，`d_k(x)` 随局部密度单调增；因此以 `c̃>τ_c` 弃权可把"低密度区检索"的假阴性率控制在由密度比决定的界内。该引理依赖支撑假设，故 E621 必须用真实 OOD 切分检验，而不能只信理论。∎

|---|---|---|
| 手势词表（E619） | 互信息增益 >0 且 ECE ≤0.05 | 退回任务 token，仅保留检索 |
| 检索增益（E620/E624） | 分布内 ≥0.05、接触 ≥0.05 | 检索降级为诊断工具，不进策略 |
| 覆盖门控（E621） | AUROC ≥0.85 且门控后 ≥基线 | **砍掉检索主线**，只留手势+审计 |
| 校准（E622） | Spearman ≥0.5、覆盖率 ∈[0.85,0.95] | 改保守阈值/停用检索 |
| 延迟（E625） | p99 ≤8 ms、降级 <0.5% | 降 K/降 C/换索引；仍不行则每 episode 只查一次 |
| 安全（E628） | 越界 0、jerk ≤1.2× | 降 ρ、λ 低通、默认关 |
| 端到端（E629） | ≥ v1 +1.5 分 | 逐项消融定位并剪枝 |

## 8. 本地实验结果（官方真机示范缓存，可复现）

**数据与任务**：15 任务 / 88 episodes / 42,646 帧；特征 = 左右 EE 位姿 12 + 夹爪 2 + 关节 14，加 3 帧差分速度（共 56 维）；目标 = 10 帧后 action 增量（28 维）。分布内按 episode 8:2 划分；OOD 按任务留出。检索 K=12，距离核 `exp(−d/2σ²)`，σ 取第 K 近邻距离中位数。脚本 `exp/gear_r2/subset.py`、`variants.py`、`retrieval_exp.py`。

| 设置 | 参数回归 R² | 检索 R² | 备注 |
|---|---|---|---|
| 分布内（总体） | 0.209 | **0.351** | 检索显著更优 |
| 难任务子集 | 0.276 | **0.411** | PlugInEthernet / Unlock / DisconnectEthernet |
| 接触阶段（夹爪<1.5） | 0.178 | **0.315** | 最后一环 |
| PlugInEthernet | 0.308 | **0.699** | 长尾接触技能 |
| OrganizeBookshelf | **0.269** | −0.064 | 检索失败案例 |
| 硬手势过滤 / 软手势 / 纯检索（同划分） | — | 0.267 / 0.275 / 0.330 | 硬过滤有害 |
| 留出任务 OOD（难组） | **0.182** | 0.021 | 检索崩塌 |
| 留出任务 OOD（易组） | 0.098 | 0.068 | 同上 |
| 检索方差–误差 Spearman | — | 0.731（接触 0.765） | 可做门控 |

**结论**：检索不是"普遍更好"，而是"在有覆盖的接触密集处显著更好、在 OOD 处崩塌"；手势不能硬过滤；检索方差是强不确定性信号。这三条直接决定了 GEAR 的"软手势 + 覆盖门控 + 残差"形态。

## 10. 风险登记册与剪枝预案

| 风险 | 概率 | 影响 | 对冲 |
|---|---|---|---|
| **检索只记忆训练分布**（OOD 无覆盖） | 高 | 高 | 覆盖门控 + 参数回退；E621 先行；不达标即砍检索主线 |
| **检索自信地错**（距离近但语义错） | 中高 | 高 | 多信号覆盖（距离+手势熵+任务纯度）+ 保形阈值 |
| **硬手势过滤伤性能** | 已实测 | 中 | 禁止硬过滤，只允许软加权（P7） |
| **延迟超预算** | 中 | 中 | chunk 级检索、HNSW、降 K、每 episode 一次 |
| **残差抖动/越界** | 中 | 中 | trust-region、λ 低通、chunk 内冻结 |
| **示范噪声/失败示范** | 中 | 中 | 只收成功 episode、按回报加权 |
| **合规质疑（外部记忆算不算单模型）** | 中 | 中 | 检索是推理期只读查表，不更新权重；提交前书面确认；保留 λ=0 纯基线 |
| **手势与任务共线** | 中 | 低 | 互信息增量检验，共线则退回任务 token |

**剪枝预案（下一轮起）**：
- **必保**：IP-09（手势软后验）、IP-11（覆盖门控）、IP-13（审计）——不依赖检索一定涨点，且反哺 v1 的 IP-02/IP-06。
- **优先深化**：IP-10/IP-12（检索库与相位对齐）——需 E620/E621 先证明覆盖可判。
- **条件推进**：若 E621 门控后仍不优于纯基线 ⇒ 检索降级为**诊断/归因工具**，主线回到 v1 的 IP-02/IP-03。
- **暂存**：大规模库、跨具身检索（无数据，不纳入本轮）。
