## 1. 两个灵感的第一性原理

### 灵感 1 ·「最小可行产品」→ 先问「谁在付房租」，而不是「还能加什么」

前三轮的主线是**加法**：第 1 轮基线、第 2 轮伺服/介入、第 3 轮状态层，清单涨到 13 项活跃 IP。在「任务面冻结、底座趋同」的窗口期做探索是合理的；但探索不等于产品。MVP 的第一性原理不是「砍功能」，而是**每一个常驻件都要证明自己覆盖了它的开销**：

- **MVP = 在预算约束下把分数做到 ε-最优的最小常驻集合**，不是「功能最少」。判据可测：把某模块拿掉，分数掉多少（收益）？它常驻时又多吃多少步数 / 时延 / 集成面（租赋）？两者之比就是它的 ROI。
- **两种开销体制决定两类模块的命运**（L14）：**常驻检测**（每个 tick 都跑，如 IP-13 低频检测、IP-14 运输滑移监测）不管触没触发都在交税，净收益 ∝ `qΔ − c_cont`，覆盖 q 越小越亏；**事件门控**（只在失败/干扰时触发，如 IP-02 介入、IP-15 响应）只为触发付钱，净收益 ∝ `q(Δ − c_act)`，**q 被约掉**。⇒ 同样的「专精」，做成门控能活，做成常驻就是税。
- **均值稀释是数学事实**（L15 的推论）：赛制按 32 任务平均，只救 1 个任务的模块对均分只贡献 Δ/32；要打平，其单任务增益必须是对一个「全任务模块」的 32 倍。不是专精无用，而是**专精必须便宜且门控**。
- **集成风险是超加的**：n 个模块的接口面可能按 n² 的交互增长。MVP 的一大半价值在于**减少能坏的地方**，而不只是减少推理次数。

一句话：本轮把「清单」改成「账本」——**常驻税要低，门控覆盖要广，集成面要小**。

### 灵感 2 ·「续航能力」→ 不是电池，而是「这套系统能撑完整场吗」

比赛里机器人是主办方的，模型由选手远程 API 部署，「续航」不能硬套电池。它有四个**可操作**的读法，且都收敛到同一个预算向量：

1. **步数续航（直接计分）**：赛制含步骤分。等待、探测、重复检测、无效 chunk 都在烧步数。续航 = 在整条 episode 内压住步数税，并在「多花 c 步换 Δp 成功率」时算得清账（L16）。
2. **时延/吞吐续航**：远程 API + 32 任务 × 多 episode 连跑。常驻检测抬高调用率 λ；服务率 μ 固定时，利用率 `ρ=λ/μ→1` 会让尾时延爆炸并触发 ACTION REJECTED。续航 = 留出 ρ 余量（L15），并过 soak 测试（E636）。
3. **泛化续航**：跨 5 个泛化轴连续评测时性能不塌方——不是「更高分」，而是「不掉档」，对应核心模块要覆盖尽量多任务（q 大）。
4. **开发续航（注意力预算）**：小团队打长赛程。每个常驻模块都在消耗调试注意力；MVP 的隐形收益是让团队还有力气跑到决赛。

**策略含义**：第 3 轮解决「该信什么」（状态层），本轮解决「信这些要花多少、能撑多久」。**续航把 MVP 从「能力子集」变成「预算可行的代谢系统」**：先活下来（IP-03 软件续航 + IP-16 预算调度），再谈长本事（IP-13/14/15 按租赋排队）。

## 2. 研究问题（新增 Q13–Q15，接第 1–3 轮 Q1–Q12）

- **Q13（模块租赋可测性）**：能否用留一消融在代理评测上稳定测出每个模块的「边际得分 / 常驻税」，且排序与「全栈 − 最小核」的真实差距一致？（E634）
- **Q14（步数续航的最优停止）**：把「继续 / 干预 / 探测 / 放弃」写成带步数影子价格的边际准则，能否在不降成功率的前提下提高步骤分？（E635）
- **Q15（运行续航）**：最小核在 32 任务 × 多 episode 的持续负载与突发时延下，能否守住 P99 预算、零 ACTION REJECTED、且时延不随 episode 单调漂移？（E636）

## 3. 设计原则（新增 P13–P15，接第 1–3 轮 P1–P12）

- **P13（付房租）**：任何常驻模块上线前必须给出「覆盖 q × 增益 Δ」与「常驻税 c_cont + q·c_act」的账；`ROI ≤ 0` 的模块只许离线存在，不许进在线主循环。
- **P14（门控优先于常驻）**：新增能力优先做成事件门控（失败/干扰触发）；常驻感知必须能被多个模块**摊薄共用**，否则默认不进 MVP。
- **P15（续航即硬约束）**：步数、P99 时延、集成面是硬约束而非软惩罚；最小核必须通过 soak 测试（E636）才允许按租赋 ROi 逐个解冻后续模块。

## 4. 清单处置（本轮以「修剪 + 两件新工具」为主）

- **运行态 MVP（在线四件套 + 基线）**：IP-03（ChunkStitch / 延迟整形 = 软件续航）＋ IP-02（抓握确认 + 门控介入 = 广覆盖低税）＋ IP-09（路标伺服；MVP 期断言退回 U13 固定阈值，不依赖 IP-13）＋ **IP-16 新增 StepBudgetGovernor（续航调度器）** ＋ 通用基线。这是本轮主张「现在就发」的最小集。
- **开发态 MVP（离线仪器）**：IP-06 代理评测 ＋ **IP-17 新增 RentLedger（租赋账本 / 留一消融）** ＋ 基线闭环。评测与记账是选择 MVP 的前置工具，不是运行时模块。
- **降级/冻结（不是删除）**：IP-13 SceneState 从「MVP 后第一扩展」降为「soak 通过后的第一候选」，且必须先过 E634 租赋测量；IP-14 / IP-15 冻结为 P2（常驻检测税高、覆盖窄），**解冻条件 = 与 IP-13 共用同一个检测器把常驻税摊薄**；IP-04 / IP-05 / IP-10 / IP-12 归入 P1 队列；IP-11 继续冻结（待 Q9 合规）；IP-01 继续条件 P1（待合规 + 算力）。
- **归档**：IP-07（已并入 IP-13）、IP-08（已并入 IP-03）维持归档；IP-09 的卡方断言（U17）在 MVP 期以 U13 固定阈值占位，IP-13 解冻后再切回。
- **本轮净变化**：活跃条目 13 → 运行态 5（含 1 新）＋ 开发态 2（含 1 新）＋ 有明确解冻条件的 P1/P2 队列。**这是「修剪」轮，不是再扩一轮。**

## 5. 本轮最大风险

**最大的风险是「用不可复核的代理评测给模块定租」：teaser 本身是脚本生成的结构性占位（exp/r16 记录 `generated_from: gen_leaderboard.py`，非基准证据），若租赋排序在真机上发生翻转，MVP 会变成「最小不可行产品」——剪掉了真正保命的低保真模块，却留下了吃延迟的伪核心。** 对冲：①租赋用多源代理（官方回放 + IsaacLab 仿真资产 + 合成注入）交叉，不以单一 teaser 为准；②先保留一个「零训练、怎么加都不会更差」的安全核（IP-03 + IP-16），只对需要训练/新增接口的模块做门控剪枝；③预注册「重加触发」（§9），E634 一旦显示某被剪模块 ROI 显著为正就无条件加回。次要风险：过剪掉只在稀有泛化轴上才发火的「保险模块」（q 小但 Δ 极大）——账本必须显式计算 `qΔ`，不能只看覆盖数。

## 6. 下一轮迭代计划（深化与修剪）

- **深化**：IP-16 的边际准则与离散规则表（E635）；IP-17 的留一/成对消融协议与交互项估计（E634）；IP-03 的 soak 压测脚本（E636）。

- **待外部事件**：不变——榜单开放日 48 h 内复核 F2/F5；规则手册可读版关闭 Q3/Q4/Q9/Q12；合规答复解锁 IP-01/IP-11。

## 5. 符号与定义（新增 U19–U22；U1–U18 沿用第 1–3 轮）

- **定义 U19（续航预算与余量）**：一次评测的预算向量 `B = (N, τ, ρ_max, φ_max)`（步数上限、P99 时延上限、服务利用率上限、集成失败面上限）。栈 S 的占用 `u(S) = (E[steps], P99_lat, ρ, φ)`，续航余量 `m_k(S) = 1 − u_k(S)/B_k`。**可行** ⇔ 对全部 32 任务 `m_k(S) ≥ m_min`（默认 `m_min = 0.15`，即至少留 15% 余量）。余量不是奢侈品：它吸收分布偏移与突发负载。
- **定义 U20（模块租赋与 ROI）**：给定参照栈 `S₋M`（去掉 M），模块 M 的覆盖 `q_M` = 在其能改变结局的 episode/task 上的占比；覆盖时增益 `Δ_M`（分）；常驻税 `c_cont(M)` = 每个 episode 都发生的步数/时延折算（分）；触发税 `c_act(M)` = 每次激活的成本（分）。**ROI**：
  `NV(M) = q_M·Δ_M − c_cont(M) − q_M·c_act(M)`。
  M 是**载荷模块（load-bearing）** ⇔ `NV(M) > 0`。所有项按影子价格换算成分：`λ_step·Δsteps + λ_lat·ΔP99 + λ_risk·Δφ`。
- **定义 U21（代谢可行 MVP）**：候选集 C，基线 B0。`S* = argmin_{S⊆C} Tax(S)`，subject to `score(S∪B0) ≥ (1−ε)·score(C∪B0)`、`S∪B0` 满足 U19 的可行性与 `m_min`；其中 `Tax(S) = Σ_{M∈S} c_cont(M) + φ(S)`。即**最小化常驻税与集成面**，而不是最少模块数。
- **定义 U22（预算调度策略）**：状态 `x = (n, p̂, ρ, U)`（剩余步数、成功概率估计、利用率、不确定度）。在每 chunk 决策 `π(x) ∈ {C, I, P, A}`（继续/干预/探测/放弃），值函数
  `V(x) = max{ 0 (A), p̂·(R_succ + r_step(n)) (C 的乐观终点), V(x − c_I, p̂ + Δp_I, ρ, U') (I), E_y[V(x − c_P, p̂⁺(y), ρ, U⁺)] (P) }`。
  **上线形态**是它的三参数离散近似（阈值 `p*`、步数上限 `n_cap`、探测白名单），DP 仅作离线上界。

## 6. 关键算法骨架（新增片段；主体沿第 1–3 轮 `UniBotSAGEPolicy`）

```python
# ===== IP-16: 续航调度器（每 chunk 一次标量决策；三参数上线形态）=====
def govern(x, theta):                       # x=(n, p_hat, rho, U)
    n, p, rho, U = x
    if n <= theta.n_min or p < theta.p_abort:          # 没预算 或 几乎必败 → 放弃
        return "ABORT"
    if rho > theta.rho_warn:                            # 服务接近饱和 → 拒绝新增探测/重估
        return "CONTINUE"
    # L16 边际准则：多花 c 步换 Δp 成功率，换算成分后是否为正
    if p < theta.p_intervene and margin_positive(p, n, theta):
        return "INTERVENE"                              # 授权 IP-02
    if U > theta.U_probe and n > theta.n_probe and p < theta.p_probe:
        return "PROBE"                                  # 授权探测（走 P12 白名单）
    return "CONTINUE"
```

```python
# ===== IP-17: 租赋账本（留一消融 + 成对交互 + ROI 排序）=====
def rent_ledger(stack, modules, evalset, seeds):
    base = score(stack, evalset, seeds)                 # 全栈基线
    rows = []
    for M in modules:
        s_minus = score(stack.without(M), evalset, seeds)
        d_score = mean(base) - mean(s_minus)            # Δscore（正=贡献）
        d_steps = steps(stack) - steps(stack.without(M))# c_cont 的步数部分
        d_p99   = p99(stack)   - p99(stack.without(M))
        d_phi   = fail_surface(stack) - fail_surface(stack.without(M))
        nv      = d_score - (lam_s*d_steps + lam_l*d_p99 + lam_r*d_phi)
        rows.append(Row(M, d_score, d_steps, d_p99, d_phi, nv))
    # 成对消融：估计超加交互（只对核内模块做，控制组合爆炸）
    interactions = pairwise(stack, core_of(rows))
    return sorted(rows, key=lambda r: -r.nv), interactions
```

```python
# ===== L16 边际规则的实现（步数影子价格版）=====
def margin_positive(p, n, theta):
    # 继续/干预预计带来 Δp 的成功率增益 vs 消耗 c 步的代价
    dV = theta.dp_est * (theta.R_succ + r_step(n)) - theta.lam_step * theta.c_chunk
    return dV > 0
```

## 7. 推导（新增引理 L14–L16；L1–L13 沿用第 1–3 轮）

**引理 L14（两种开销体制的 ROI 分界）** 设模块覆盖比例为 q、覆盖时增益 Δ、常驻税 c_cont、触发税 c_act。
(i) 常驻检测型：`NV = qΔ − c_cont`，净正 ⇔ `Δ > c_cont/q`；q→0 时所需 Δ→∞。
(ii) 事件门控型：`NV = q(Δ − c_act)`，净正 ⇔ `Δ > c_act`，**q 被约掉**。
⇒ 同样的专精能力，做成门控可存活，做成常驻则是税；常驻感知必须由多个消费者摊薄（`c_cont` 只付一次，q 取并集）。∎

**引理 L15（均值稀释与利用率上限）**
(i) 赛制目标为 `score = (1/N)Σ_i s_i`（N=32）。只改变集合 A（|A|=qN）的模块对均分贡献 `qΔ`；要敌过增益 δ 的全任务模块，需 `Δ > δ/q`。q=1/32 时需 32 倍单任务增益。
(ii) 工作守恒服务器上，新增调用率 δ 使利用率 `ρ=(λ+δ)/μ`；尾时延近似随 `ρ/(1−ρ)` 增长。要守住 P99 预算，需 `ρ ≤ ρ_max`；越过则任何能力收益都必须先抵扣「尾时延诱发的失败增量」，通常为负。
⇒ 专精模块的生存空间是「门控 + 极低触发税」；常驻高覆盖模块才是 MVP 的默认解。∎

**引理 L16（步数续航的边际停止准则）** 在剩余 n 步、成功概率 p̂ 处，多花 `c` 步做一次干预/探测，带来成功率增益 `Δp`，记成功+步骤分的终端价值为 `R_succ + r_step(n)`、步数影子价格为 `λ_step`，则期望增益
`ΔV = Δp·(R_succ + r_step(n)) − λ_step·c`。
当 `ΔV > 0` 才值得花这 c 步；对固定的 c，存在盈亏平衡成功率 `Δp* = λ_step·c / (R_succ + r_step(n))`。ABORT 是 C 的退化：当 `p̂·(R_succ + r_step(n)) < λ_step·c_remaining`（且无部分分）时，放弃优于继续。⇒ 调度器把「介入/探测/保持/放弃」统一成同一个边际不等式；离散规则表是它的分段线性近似。∎
