# 第 8 轮（新循环第 1 轮）· METRIC-PILOT：位姿图把语义接到度量，关节残差把度量接到执行，仿真孪生把两者校准

> 检索/复核日期：2026-10-26（UTC）。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、5 条泛化轴、通才单模型、自部署 + 官方远程真机 API。按状态文件连续编号为第 8 轮；按用户的新循环计数为第 1 轮。本轮三个灵感词是「关节驱动」「位姿估计」「虚拟仿真」。

## 0. 先把三个词钉到本轮新核实的事实上

### 0.1 关节驱动：数据集 `info.json` 的关节名称是错的，实际数值是官方 URDF 顺序

这是本轮最硬、也最容易被忽略的发现。HangCup 的 `meta/info.json` 把左臂 7 个关节命名为：

```text
[shoulder_pitch, shoulder_roll, shoulder_yaw, elbow, wrist_yaw, wrist_roll, wrist_pitch]
```

但官方 G1 Dex1 URDF 的运动链顺序是：

```text
[shoulder_pitch, shoulder_roll, shoulder_yaw, elbow, wrist_roll, wrist_pitch, wrist_yaw]
```

我拿 HangCup 前 20 帧做 FK 对比（`g1_29dof_mode_15_with_dex1_1.urdf`，`left_dex1_base_link` 为末端）：

- 按 **URDF 顺序**直接映射：末端姿态误差恒为 **0**，位置只差一个固定平移 `[0.0635, 0, 0] m`（std 为 0）；
- 按 **info.json 名称顺序**映射：姿态误差巨大，且随帧变化；
- 同一个 URDF 的 `torso_link` FK 与 `state_torso` **逐位完全相等**；
- `state_d435` 在 torso 系下的相对位姿与 URDF `d435_joint` 完全相等（`xyz = [0.0576235, 0.01753, 0.42987]`，`pitch = 0.8307767 rad`）；base 系值 = `T_base_torso × d435_joint`；
- `left_ee_pose_gripper_base` = `left_dex1_base_link` FK + `[0.0635, 0, 0] m`，旋转零误差。

结论：**数据本身没有错，错的是 `info.json` 的名称标注；实际臂关节数值就是 URDF 顺序，`gripper_base` 是 Dex1 base 沿 x 前移 6.35 cm 的固定点。** 这带来两个直接后果：

1. 这是一个**接口级隐患**：如果评测端的 joint action 顺序按 `info.json` 名称实现，腕部三轴会被交换，腕部姿态会错，所有精密任务都会受损；如果评测端与数据集一致（URDF 顺序），则没问题。必须用单任务调试槽做一次“小角度探测 + FK 对比”审计。
2. 这也是一个**免费的度量先验**：相机、躯干、EE 的外参都已经在观测里，且与 URDF 精确一致。位姿估计不需要从零标定机器人，只需要标定“物体/容器”和“腕部相机”。

这条发现把「关节驱动」从“控制器调参”提升为“**运动学接口自检 + 关节空间残差执行**”：先保证顺序/符号/零位对，再谈控制。

### 0.2 位姿估计：官方观测已经给出相机/躯干/EE 的度量位姿，缺的是物体位姿和深度

UniBot 的 API 观测里有 `state_torso`、`state_d435`、`left/right_ee_pose_gripper_base`、双臂关节、夹爪、`lower_body`。上一节已经证明：这些量与官方 URDF 精确一致。因此：

- **头部 D435 的位姿是已知量**，不需要视觉里程计；`head_stereo_left/right` 相对 D435 的外参/基线仍需标定；
- **EE 位姿是已知量**，不需要手眼标定整条臂；
- 缺的是：`head_stereo` 相对 D435 的外参、头部相机的内参/双目基线、腕部相机相对 Dex1 的安装外参、物体/容器的 6D 位姿、以及没有 depth 的度量深度。

本轮核实到的可行性证据：

- 官方仿真栈给出头部相机 `d435_link/front_cam` 的标称内参（`focal_length=7.6 mm`、`horizontal_aperture=20 mm`、640×480），以及腕部相机相对 `left_hand_base_link` 的标称安装（`pos_offset=[0.02541028, 0.045, 0.135]`，四元数 `[-0.34202, 0.93969, 0, 0]`）。这些是**先验**，不是真机标定值，但足以做初始化。
- G1 + Dex3 的公开位姿管线（SAM 3D 重建网格 + FoundationPose 零样本 6D 跟踪 + Unity IK）在静态场景做到 `σ_xyz=1.05 mm`、部分遮挡 `6.40 mm`，15–17 fps。它用的是 RGB-D；UniBot 没有 depth，但这条管线证明了“G1 + 基础模型位姿 + 关节执行”的工程可行性，我们只需要把 RGB-D 换成双目/单目度量深度，并用已知的 `state_d435` 做相机位姿/尺度锚定（`head_stereo` 与 D435 的相对外参需标定）。
- HangCup 的工作空间很紧凑：EE 的 z 只有 0.066–0.147 m，头部相机 z=0.456 m，躯干 z=0.044 m。1 cm 的位姿误差在这个尺度上就是“能不能挂上”的差别。若头部双目基线为 5–10 cm、焦距按仿真 243 px 或 D435 约 605 px 估算，0.4 m 处 0.5 px 视差误差对应约 **1.3–6.6 mm** 深度误差；腕部相机在 0.1–0.2 m 处更细，配合已知 CAD/ICP 可到亚厘米。这个量级足够支撑“粗定位 + 局部精修”的两级位姿图。

所以「位姿估计」在本方案里不是“再训一个 FoundationPose”，而是：**用已知的机器人 proprioception 做度量骨架，用头部双目做全局粗位姿，用腕部相机 + EE 做局部精位姿，再用一个与 VLA 共享 backbone 的位姿头把学习部分压进单 checkpoint。**

### 0.3 虚拟仿真：官方仿真栈 + 数据集 URDF 可以校准，但只做标定/反事实，不做全任务孪生

本轮核实到的官方仿真资产：

- `unitree_sim_isaaclab` 有 G1 + Dex1 的 pick/place、stack 任务，头部/腕部相机配置，以及 `d435_link`、`left_hand_base_link` 的相机挂点；
- `unitree_lerobot` 有官方 IK、头部图像左右切分、相机键名；
- `unitree_ros` 有 Dex1 的 URDF，与数据集的外参精确一致。

更关键的是 2026 年的 sim-to-real 证据：

- **10k+ 真机试验的实证研究**：空间特征（桌面高度、相机位姿）比外观（背景纹理、光照）更能提升零样本迁移；frame-wise 域随机化优于 episode-wise；保真度有帮助但边际递减；RL 微调把真机成功率从 5.6% 提到 33.4%，加域随机化到 42.8%。这直接告诉我们：**仿真预算应优先花在“相机/桌面/机器人几何”的校准和空间随机化，而不是 photorealism。**
- **VIRAL**：G1 + D435i，delta action、相机对齐、大规模视觉域随机化，零样本真机连续 loco-manipulation 54/59 次。它证明 G1 的视觉 sim-to-real 可行，但也说明需要 64 GPU 级算力；我们只借用它的“delta action + 相机对齐 + 空间随机化”结论，不复制它的 RL 规模。
- **Sim2Real-VLA**：纯仿真训练、真机 60.8%，比最佳基线高 35pp；核心是 affordance 链 + 双系统，而不是高保真渲染。这支持我们把仿真当作“位姿标签/反事实发生器”，而不是策略 oracle。

因此「虚拟仿真」在本方案里是 **SCT（Sim-Calibrated Twin）**：只对 5–8 个高精度任务建孪生，做三件事——相机/桌面/关节标定、物体 6D 位姿标签、5 轴反事实；不做 32 任务全高保真孪生，不做运行时 MPC，不把仿真 RL 放进主路径。

## 1. 失败模型：<30% 不是语义不够，而是语义到度量、度量到关节执行之间缺一层

先看头部模型在公开 benchmark 上的真实位置（RoboChallenge Table30，2026-02 数据）：

| 模型 | 类型 | 成功率 | 备注 |
|---|---|---:|---|
| Era0 / Robotera | specialist | 64.33% | 榜首 |
| DM0 / Dexmal | specialist | 62.00% | 2.4B，空间 CoT |
| GigaBrain-0.1 | specialist | 51.67% | RGBD + world model 数据 |
| Spirit-v1.5 | specialist | 51.00% | Qwen3-VL-4B + DiT |
| π0.5 | specialist | 42.67% | 高层子任务 co-training |
| DM0_generalist | generalist | 37.33% | 同一模型跨 30 任务 |
| wall-oss-v0.1 | generalist | 35.33% | 4B，20+ 本体 |
| π0 | generalist | 28.33% | 早期基线 |

这张表说明两件事：

1. **通才-专家差距约 25pp**（37.3% vs 62.0%），而且差距集中在插拔、拉链、折叠、擦拭、三明治这类**接触/精密/长程**任务。UniBot 的占位榜首 29.7% 不是真实数据，但它与“通才 30–37%”这个量级吻合；真实 UniBot 大概率也在这个区间。
2. **头部模型已经不缺语义**：MolmoAct2 有 3D 推理和 37× 加速，WALL-OSS 零样本 60.5% task progress，DreamZero 用 video world model 做到 2× 泛化，Spirit 用 Qwen3-VL 做到 Table30 前列，DM0 用空间 CoT 把 2.4B 做到 62% 专家。它们缺的是：**闭环的度量状态、关节级的执行修正、以及失败后的谓词级恢复**。

把失败拆成四类：

| 失败类 | 典型表现 | 现有头部模型 | 本方案 |
|---|---|---|---|
| 语义 | 选错物体/子任务/目标 | 强（VLA/CoT） | SSG + VLA 保留 |
| 度量 | 物体对了，6D 位姿/深度/尺度错 | 弱（2D bbox/EEF 轨迹） | **MPG 位姿图** |
| 执行 | 目标对了，关节跟踪/接触/奇异点错 | 弱（开环 chunk、EE 绝对） | **JRS 关节残差** |
| 验证/恢复 | 掉了/被人移走/假完成 | 弱（无谓词、无重试） | SVL + PPR + NRB |

UniBot 占位数据里“步骤分 − 成功率”平均约 +8.6pp（39.0−29.7 等），说明失败多发生在后段；真实 RoboChallenge 的 per-task 数据也显示 `plug_in_network_cable`、`fold_dishcloth`、`make_vegetarian_sandwich`、`wipe_the_table` 这类任务接近 0–20%。这与“语义不够”不一致，更像“最后几厘米/最后一步”的度量与执行问题。

## 2. 主判断：给语义 VLA 加一层“度量-执行”外骨骼，而不是再换一个更大的 VLA

本轮的主判断是：

> **UniBot 的 <30% 不是语义不够，而是语义到度量、度量到关节执行之间缺一层。给现有 VLA 加一个“单 checkpoint 位姿头 + 确定性度量位姿图 + 关节空间残差伺服”的外骨骼，再用一个只做标定/反事实的仿真孪生校准，能以远低于再训一个大 VLA 的成本，把精度失败转成可恢复的闭环。**

为什么是这三件套，而不是别的：

- **为什么不是更大的 VLA**：头部模型已经在语义/泛化上很强；再大一号的 VLA 仍然没有显式度量状态，仍然开环执行 chunk，仍然在接触任务上丢精度。RoboChallenge 的通才-专家差距说明“数据/模型规模”不是唯一瓶颈，专家模型也才 62%。
- **为什么是 joint-space**：2026 年的大规模动作空间研究（13,000+ 真机 rollout、500+ 模型）给出清晰结论：delta action 一致优于 absolute；joint-space 在固定本体上更鲁棒，task-space 在跨本体迁移上更好；flow matching 在 joint-space 收益最大。UniBot 是单一本体（G1），所以默认 **joint + chunk-wise delta**；位姿图提供 task-space 的度量修正，两者互补。
- **为什么位姿头必须进同一个 checkpoint**：手册要求“所有任务基于同一模型，不得混合多个模型”。独立 FoundationPose/SAM 推理有合规风险；把位姿头挂在 VLA 共享视觉 backbone 上，推理时只有一个 checkpoint，位姿图/伺服是确定性代码，仿真只在离线。这是最干净的合规路径。
- **为什么仿真只做标定/反事实**：10k+ 真机试验说明空间校准比外观保真更重要；VIRAL/Sim2Real-VLA 说明仿真可以补数据，但需要大规模算力和精心设计。我们的算力/时间不允许全任务孪生，所以只对高精度任务建孪生，把仿真用在“相机/桌面/关节标定、位姿标签、5 轴反事实、伺服验证”四件事上。

## 3. 方案轮廓：METRIC-PILOT

```text
语言（32×5=160 条复述之一） → SSG 评分步骤图 → 当前步骤 s
                                      │
                    ┌─────────────────▼─────────────────┐
                    │ MPG 度量位姿图                     │
                    │  头部双目 → 物体/容器 6D（粗）      │
                    │  腕部相机 + EE → 物体 6D（精）      │
                    │  state_torso/d435 → 相机位姿（已知）│
                    │  PCH 位姿头（同一 checkpoint）      │
                    └─────────────────┬─────────────────┘
                                      ▼
        VLA（单一 checkpoint）：action head → joint delta chunk
                                      │
                                      ▼
        JRS 关节残差伺服：Δq = Δq_VLA + J⁺(K_p e_pose) + 限幅/平滑/柔顺
                                      │
                                      ▼
        SVL 落点闭环 + PPR 位姿谓词恢复 + NRB 官方备注恢复
                                      │
                                      ▼
        SCT 仿真孪生：标定相机/桌面/关节，生成位姿标签/5 轴反事实，验证伺服
```

组件分工：

| 组件 | 作用 | 进推理？ | 类型 |
|---|---|---|---|
| **MPG** 度量位姿图 | 融合头部/腕部/EE/相机位姿，输出物体/容器/夹爪的 6D 状态 | 是 | 确定性优化 + 学习位姿头 |
| **PCH** 位姿条件头 | 在 VLA 共享 backbone 上回归 6D 位姿/关键点/深度 | 是 | 同一 checkpoint 的辅助头 |
| **JRS** 关节残差伺服 | 把位姿误差映射为关节残差，限幅/平滑/柔顺后叠加到 VLA 关节目标 | 是 | 确定性控制 |
| **SCT** 仿真标定孪生 | 标定相机/桌面/关节；生成位姿标签/5 轴反事实；验证伺服 | 否 | 离线 |

| **SRL** 交互可信度护盾 | 限制 jerk/离群动作/延迟抖动，保证动作流规整 | 是 | 确定性代码 |
| **SSG** 评分步骤图 | 官方步骤/权重 → 状态机/谓词，防跳步/假完成 | 是 | 确定性代码 |
| **PGL** 放置目标阶梯 | 槽位 → 2D 锚点 → 6D 位姿；由 MPG 升级 | 是 | 确定性代码 |
| **OPT** 位姿先验迁移 | K 条演示的“容器系释放位姿”中位数/离散度 → 当前目标 | 是 | 查表/统计 |
| **ICR** 上下文检索 | 关系中心键 + 相位对齐 + 缓存编码 | 是 | 数据，不是模型 |
| **SVL** 落点闭环 | 伺服→缓放→稳定性校验→重试/重抓 | 是 | 控制循环 |
| **PPR** 位姿谓词恢复 | 用 MPG 的 6D 谓词判断“掉了/歪了/没插到底”，触发恢复 | 是 | 确定性代码 |
| **NRB** 官方备注恢复库 | 用公开 human 备注构造破坏→恢复对 | 否 | 训练数据 |
| **L2L** 实验室数据协议 | 伙伴实验室采集背景/位置多样性数据 | 否 | 流程 |
| **DebugLoop** | 不计分单任务调试槽作发布门 | 否 | 流程 |

保留/升级/修剪：

- **保留**：SSG、ICR、SVL、NRB、L2L、DebugLoop、GPR-VLA 主干、WLA-1.0-Base 底座、TLE/ACP/GF 数据引擎、AH-TP、Endurance Governor、Compliance Compiler。
- **升级**：PGL → MPG（2D 锚点升级为 6D 位姿图）；OPT → 位姿先验因子（不再只是释放位姿统计）；SVL → 位姿谓词闭环；TCLB → 离线相对比较工具；FLEET → 工程检查单。
- **新增**：MPG、PCH、JRS、SCT、KSI、SRL、PPR。
- **修剪**：32 任务全高保真孪生、自由仿真数据、运行时仿真/MPC、仿真 RL 主路径、布料/拉链/透明全物理、WMA-0 进主路径、每任务 LoRA。

## 4. 统计修正：不要再承诺“3pp 80%”

上一轮把“+3pp、80% 把握”当作目标，这是错的。320 个计分 trial（32×10）在 p≈0.3 时：

- 单组成功率的标准误约 `sqrt(0.3×0.7/320)=2.56pp`；
- 两组独立比较的差标准误约 `sqrt(2×0.3×0.7/320)=3.62pp`；
- 80% 单侧把握大约需要 **10pp** 的差；配对设计（同一任务/同一初始条件）可把方差降下来，若不一致率 20%，差标准误约 2.5pp，80% 把握约需 **7pp**；不一致率 10% 时约需 **5pp**；
- 要可靠检测 3pp，配对设计也需要约 1,700+ trial，单次提交做不到。

所以本轮的实验设计是：**主目标 +7–10pp，或“在 5–8 个高精度任务上 +15–20pp”**；不再用 3pp 做承诺。调试槽的 A/B 优先看任务级显著性，而不是总分的小数点。

## 5. 风险与合规

- **单模型**：默认 C1——一个 VLA checkpoint，内含 action/pose/step 三个头；MPG/JRS/KSI/SRL/SSG 都是确定性代码；SCT 只在离线；FoundationPose/SAM 3D 只用于离线打标签。若规则明确允许独立位姿模型，再升级到 C3；否则不碰。
- **外部数据**：默认只用官方 32 数据集 + 官方仿真资产；伙伴实验室自采数据挂在合规开关后（C2）；仿真数据只做预训练/校准，最终在官方数据上微调；若规则禁止外部数据，回退 C0（官方数据 + 2D 锚点/自监督位姿头）。
- **位姿头在透明/布料/拉链上可能失效**：这些任务退回 2D 锚点/关键点 + SSG/SVL，不强推 6D。
- **头部双目内参/基线未知**：先用仿真标称 + 已知相机运动自标定；失败则用单目度量深度（Depth Anything 3 / Depth Pro 等）+ 桌面平面/EE 尺度锚定；再失败则只用腕部相机 + EE。
- **评测端关节顺序未知**：用调试槽做小角度探测；KSI 在运行时被动检测“命令顺序 vs 观测变化”的不一致；若发现交换，立即 remap。

## 1. 本轮新核实的事实（一手）

### 1.1 关节顺序：`info.json` 名称错，数据是官方 URDF 顺序

HangCup `meta/info.json` 的左臂关节名：

```text
[shoulder_pitch, shoulder_roll, shoulder_yaw, elbow, wrist_yaw, wrist_roll, wrist_pitch]
```

官方 `g1_29dof_mode_15_with_dex1_1.urdf` 的运动链：

```text
[shoulder_pitch, shoulder_roll, shoulder_yaw, elbow, wrist_roll, wrist_pitch, wrist_yaw]
```

用 HangCup 前 20 帧做 FK，以 `left_dex1_base_link` 为末端，比较两种映射：

| 假设 | 映射方式 | 姿态误差 | 位置误差 |
|---|---|---:|---:|
| A：按 info 名称 | 数据第 5/6/7 维 → URDF `wrist_yaw/wrist_roll/wrist_pitch` | 大且随帧变化 | 大 |
| B：按 URDF 顺序 | 数据第 5/6/7 维 → URDF `wrist_roll/wrist_pitch/wrist_yaw` | **恒为 0** | 固定偏移 `[0.0635, 0, 0] m`，std=0 |

同一 URDF 的交叉验证：

| 量 | 数据字段 | FK/URDF 结果 | 误差 |
|---|---|---|---:|
| 躯干位姿 | `state_torso` | `torso_link` FK（waist_yaw/roll/pitch） | 逐位 0 |
| 头部 D435 位姿 | `state_d435` | `T_base_torso × d435_joint`：`xyz=[0.0576235, 0.01753, 0.42987]`，`pitch=0.8307767`（torso 系） | 逐位 0 |
| 左 EE 位姿 | `left_ee_pose_gripper_base` | `left_dex1_base_link` FK + `[0.0635, 0, 0]` | 旋转 0；平移 std=0 |

结论：

1. **数据值本身是 URDF 顺序；`info.json` 的腕部名称标错了。** 这不是数据损坏，而是文档/元数据 bug。
2. `gripper_base` 是 Dex1 base 沿 x 前移 **6.35 cm** 的固定点，旋转与 Dex1 base 相同。
3. 评测端如果按 `info.json` 名称实现 joint action，腕部三轴会交换；如果按数据集/URDF 顺序实现，则一致。**必须用调试槽做一次小角度探测审计**（见 §3.7 KSI）。
4. 这条发现同时给了我们精确的相机/躯干/EE 外参，是 MPG 的度量骨架。

### 1.2 相机/EE 外参：proprioception 已经给出度量骨架

- **头部 D435**：`state_d435` 就是 `d435_link` 在 base 系的位姿；把 torso FK 乘上 `d435_joint` 后与 `state_d435` 逐位一致。头部 D435 位姿不需要视觉估计；`head_stereo_left/right` 相对 D435 的外参/基线仍需标定。
- **EE**：`left/right_ee_pose_gripper_base` 与 URDF FK 精确一致；`gripper_base = dex1_base + 6.35cm x`。
- **躯干**：`state_torso` 与 waist 三关节 FK 精确一致；`lower_body` 最后三维就是 waist_yaw/roll/pitch。
- **腕部相机**：官方仿真资产给出标称安装（相对 `left_hand_base_link`）：
  - 左：`pos_offset=[0.02541028, 0.045, 0.135]`，四元数 `[-0.34202, 0.93969, 0, 0]`；
  - 右：`pos_offset=[-0.02541028, 0.045, 0.135]`，同一旋转；
  - 这是**先验**，不是真机标定值；需要用数据集/真机手眼标定确认。
- **头部相机内参/双目基线**：数据没有给。官方仿真给出 `focal_length=7.6 mm`、`horizontal_aperture=20 mm`、640×480，对应 `fx≈243.2 px`；真实 D435 RGB 约 `fx≈605 px`。`unitree_lerobot` 的 `make_robot.py` 把一张头部宽图按水平切成左右两半，说明“head_stereo_left/right”可能是双目并排或单幅宽视场；基线/内参必须自标定。

**工作空间尺度**（HangCup 前 42 帧）：

| 量 | 范围（base 系） |
|---|---|
| 左 EE xyz | x 0.264–0.310，y 0.042–0.278，z 0.066–0.147 |
| 右 EE xyz | x 0.239–0.273，y −0.299–−0.277，z 0.095–0.118 |
| 躯干 xyz | x −0.004，y 0，z 0.044 |
| 头部相机 xyz | x 0.130，y 0.018，z 0.456；pitch 1.011 rad |

在这个尺度上，1 cm 的位姿误差就是“能不能挂上”的差别。双目深度误差估算（0.4 m 处、0.5 px 视差误差）：

| 焦距 | 基线 | 深度误差 |
|---:|---:|---:|
| 243 px | 5 cm | ≈6.6 mm |
| 243 px | 10 cm | ≈3.3 mm |
| 605 px | 5 cm | ≈2.6 mm |
| 605 px | 10 cm | ≈1.3 mm |

所以头部双目足够做**全局粗位姿**；腕部相机在 0.1–0.2 m 处做**局部精位姿**，配合已知 CAD/ICP 可到亚厘米。这正是 MPG 的“粗到精”结构。

### 1.3 动作空间：joint + delta 是单本体场景的默认最优

2026 年的大规模动作空间研究（13,000+ 真机 rollout、500+ 模型、四个场景）结论：

- **delta action 一致优于 absolute action**，chunk-wise delta 比 step-wise 更稳；
- **joint-space 在固定本体上更鲁棒**，尤其与 flow matching 结合时收益最大；task-space 在跨本体/迁移场景更有优势；
- 动作 chunk 的执行长度要与时间抽象匹配，不能把 chunk 当孤立常数。

UniBot 是单一本体 G1，评测 32 任务 × 5 轴，不需要跨本体迁移；因此默认 **joint + chunk-wise delta**。这与官方 API 的 `control_space="joint"` 完全一致。MPG 提供 task-space 的度量修正，JRS 把它映射回关节空间，兼顾“joint 的执行鲁棒性”和“task 的度量精度”。

## 2. 失败模型与假设

### 2.1 四类失败

| 失败类 | 典型表现 | 现有头部模型 | 本方案 |
|---|---|---|---|
| 语义 | 选错物体/子任务/目标 | 强（VLA/CoT） | SSG + VLA 保留 |
| 度量 | 物体对了，6D 位姿/深度/尺度错 | 弱（2D bbox/EEF 轨迹） | **MPG 位姿图** |
| 执行 | 目标对了，关节跟踪/接触/奇异点错 | 弱（开环 chunk、EE 绝对） | **JRS 关节残差** |
| 验证/恢复 | 掉了/被人移走/假完成 | 弱（无谓词、无重试） | SVL + PPR + NRB |

### 2.2 为什么 <30% 是度量/执行/验证，不是语义

- RoboChallenge 通才-专家差距 25pp，专家模型也只有 62%；如果语义是主要瓶颈，专家模型不会只有 62%。
- UniBot 占位数据“步骤分 − 成功率”平均 +8.6pp，说明失败多在后段；真实 RoboChallenge 的 `plug_in_network_cable`、`fold_dishcloth`、`make_vegetarian_sandwich`、`wipe_the_table` 等任务接近 0–20%，都是接触/精密/长程。
- 头部模型已经把 3D 推理、depth token、world model、空间 CoT 都做进去了；它们缺的不是“看懂”，而是“量准 + 补正 + 验完”。

### 2.3 六个可证伪假设

| ID | 假设 | 检验 | 若成立 | 若不成立 |
|---|---|---|---|---|
| H1 | 精度任务的主要失败是 6D 位姿误差 >1cm/5° | 在 T01/T10/T27 上测位姿误差 vs 成功 | MPG 优先 | 退回 2D 锚点 |
| H2 | joint delta + 残差伺服优于 EE absolute | 调试槽 A/B：VLA-only vs +JRS | JRS 进主路径 | 保留 VLA joint，去掉 JRS |
| H3 | 空间校准/随机化比外观更能提升 5 轴 OOD | 仿真 A/B：空间 vs 外观 | SCT 聚焦几何 | SCT 只做标签 |
| H4 | 评测端 joint 顺序与数据集一致 | 小角度探测 + FK | KSI 只做保险 | 立即 remap |
| H5 | 单 checkpoint 位姿头不伤 action | 训练 A/B：有无 pose loss | PCH 合规可行 | 位姿只离线/申请独立模型 |
| H6 | 5–8 个高精度任务的提升能外溢到其余任务 | 全量 320 trials 分层分析 | 扩孪生范围 | 只保高精度任务 |

### 2.4 统计功效修正

320 个计分 trial（32×10），p≈0.3：

| 设计 | 差标准误 | 80% 单侧把握可检测 |
|---|---:|---:|
| 两组独立 | ≈3.62pp | ≈10pp |
| 配对，不一致率 20% | ≈2.5pp | ≈7pp |
| 配对，不一致率 10% | ≈1.77pp | ≈5pp |
| 配对，检测 3pp | — | 需约 1,700+ trial |

所以本轮主目标是 **+7–10pp 总体，或 5–8 个任务 +15–20pp**；不再承诺“3pp 80%”。调试槽优先看任务级显著性。

## 3. 方法：METRIC-PILOT

### 3.1 总览

```text
语言（160 条复述） → SSG 步骤图 → 当前步骤 s / 谓词 P
                                      │
                    ┌─────────────────▼─────────────────┐
                    │ MPG 度量位姿图                     │
                    │  变量：物体 O、容器 C、夹爪 G       │
                    │  因子：头部双目、腕部相机、EE、相机 │
                    │  求解：鲁棒因子图 + 时序平滑        │
                    └─────────────────┬─────────────────┘
                                      ▼
        VLA（单 checkpoint）：action head → joint delta chunk
        PCH 位姿头：共享视觉 token → O/C/G 6D / keypoints / depth
                                      │
                                      ▼
        JRS：Δq = Δq_VLA + J⁺(K_p e_pose + K_d e_vel) + 限幅/平滑/柔顺
                                      │
                                      ▼
        SVL/PPR：落点闭环 + 位姿谓词恢复 + NRB 官方备注恢复
                                      │
                                      ▼
        SCT：相机/桌面/关节标定；位姿标签；5 轴反事实；伺服验证
```

### 3.2 MPG：度量位姿图

**变量**：

- `T_base_obj`：目标物体 6D 位姿；
- `T_base_con`：容器/目标槽位 6D 位姿；
- `T_base_grip`：夹爪 6D 位姿（由 `left/right_ee_pose_gripper_base` 直接给，或由关节 FK 给）；
- `T_base_cam_head`：头部 D435 位姿（由 `state_d435` 给，固定因子）；若 `head_stereo` 与 D435 不同，再乘标定外参 `T_d435_headstereo`；
- `T_hand_cam`：腕部相机相对 Dex1 base 的外参（标定因子，可带 slack）；
- `T_obj_keypoints`：物体关键点/语义点（可选）。

**因子**：

| 因子 | 来源 | 残差 | 鲁棒核 |
|---|---|---|---|
| 头部双目 | `head_stereo_left/right` + 内参/基线 | 重投影/视差 | Huber |
| 头部单目深度 | PCH depth 或 DA3/Depth Pro | 尺度/逆深度 | Huber |
| 腕部相机 | `wrist_left/right` + 手眼外参 | 重投影/相对位姿 | Huber |
| EE 先验 | `left/right_ee_pose_gripper_base` | `T_base_grip` 先验 | 固定/高权重 |
| 相机先验 | `T_base_torso × d435_joint` | 头部 D435 位姿先验 | 固定 |
| 桌面平面 | 标定/点云 RANSAC | 点到平面距离 | Huber |
| 时序平滑 | 上一帧 `T` | 相对运动/速度 | Huber |
| 容器/物体先验 | OPT 的 K 条演示统计 | 相对位姿先验 | Huber |
| 碰撞/可达 | URDF + 关节限位 | 距离/限位 | 硬约束 |

**求解**：

- 每帧先用 PCH 位姿头给 `T_base_obj`/`T_base_con` 初值；
- 用头部双目/单目深度做 2D-3D 对应，鲁棒 ICP/EPnP  refine；
- 腕部相机在抓取/放置阶段提供局部高精度因子；
- 因子图用 `gtsam`/`ceres`/自写 Gauss-Newton，变量维度小（3–6 个 6D 位姿），单帧 1–3ms；
- 失败处理：若内点率 <30% 或重投影误差 >5px，标记 `pose_valid=false`，退回 2D 锚点 + SVL，不把错误位姿喂给 JRS。

**伪代码**：

```python
def mpg_step(obs, prev_state, pch, calib):
    # 1. 已知量
    T_base_cam = obs.state_d435          # D435 base pose; head_stereo needs T_d435_headstereo
    T_base_grip_l = obs.left_ee_pose     # exact from FK
    T_base_grip_r = obs.right_ee_pose
    # 2. 学习先验
    pose_prior = pch(obs.images, obs.language, obs.proprio)
    # 3. 视觉因子
    factors = []
    if calib.head_stereo_valid:
        factors += stereo_factors(obs.head_left, obs.head_right,
                                  calib.head_intr, calib.head_baseline,
                                  pose_prior, T_base_cam)
    factors += wrist_factors(obs.wrist_left, obs.wrist_right,
                             calib.hand_cam, T_base_grip_l, T_base_grip_r)
    factors += prior_factors(pose_prior, prev_state, opt_prior)
    factors += table_plane_factor(calib.table_plane)
    # 4. 鲁棒求解
    state = robust_factor_graph.solve(factors, init=pose_prior)
    state.pose_valid = state.inlier_ratio > 0.3 and state.reproj < 5.0
    return temporal_smooth(state, prev_state)
```

### 3.3 PCH：单 checkpoint 位姿头

**为什么放在同一 checkpoint**：手册“所有任务基于同一模型，不得混合多个模型”。独立 FoundationPose/SAM 3D 推理有合规风险；把位姿头挂在 VLA 共享视觉 backbone 上，推理时只有一个 checkpoint。位姿图/伺服是确定性代码，仿真只在离线。

**结构**：

```text
images (4 RGB) + language + proprio
        │
   VLA visual/language backbone（共享）
        │
   ┌────┴──────────────┬────────────────┬──────────────┐
   ▼                   ▼                ▼              ▼
action head       pose head         step head      depth head (optional)
(joint delta)     (O/C/G 6D + kp)   (subtask/pred) (metric depth)
```

**输出**：

- 物体/容器 6D：`t∈R³` + 6D rotation（连续表示，避免四元数符号跳变）；
- 关键点：物体/容器 8–12 个语义点，用于 2D 重投影；
- 夹爪相对物体：`T_grip_obj`，用于抓取/放置；
- 可选 depth：头部相机的度量深度，给 MPG 做单目因子；
- 可选 mask：目标物体/容器分割，给 ICP/位姿 refine。

**损失**：

```text
L = L_action + λ1 L_pose + λ2 L_kp + λ3 L_step + λ4 L_consistency + λ5 L_depth
L_pose = L_rot_geodesic + L_trans_L1 + L_add_s (对称物体)
L_kp = L_reproj + L_depth_kp
L_consistency = || FK(q) - EE_reported ||² + || T_pose_graph - T_head ||²
L_step = CE(step, label) + BCE(predicate, label)
```

**训练标签**：

- 官方数据：EE 位姿、相机位姿、关节 FK 是精确标签；物体/容器位姿用 SCT/SAM 3D/FoundationPose 离线打；
- 仿真数据：渲染时已知物体/容器 6D，直接监督；
- 真实无标签帧：用 MPG 的因子图输出做伪标签，置信度过滤（内点率、重投影、时序一致）；
- 透明/布料/拉链：不回归 6D，改回归关键点/affordance/2D 锚点，避免不可辨识。

**合规**：PCH 是同一 checkpoint 的辅助头；推理时只加载一个模型。若规则允许独立位姿模型，可把 PCH 换成 FoundationPose/SAM 3D（C3）；默认不做。

### 3.4 JRS：关节空间残差伺服

**核心**：VLA 输出 joint delta chunk `Δq_VLA`；MPG 给出目标位姿 `T*` 与当前位姿 `T` 的误差 `e_pose`；用阻尼最小二乘/雅可比伪逆把 `e_pose` 映射为关节残差 `Δq_geo`；叠加、限幅、平滑、柔顺后下发。

```text
e_pose = log(T* T⁻¹)                      # 6D twist
Δq_geo = J⁺(q) (K_p e_pose + K_d e_vel)   # 阻尼最小二乘
Δq_raw = Δq_VLA + α Δq_geo
Δq = clip(Δq_raw, v_max dt, q_min - q, q_max - q)
Δq = smooth(Δq, jerk_max, prev_Δq)
q_cmd = q + Δq
```

**关键设计**：

- **关节顺序 remap**：JRS 内部用 URDF 顺序 `[sp,sr,sy,elbow,wrist_roll,wrist_pitch,wrist_yaw]`；若评测端/数据集顺序不同，KSI 在入口 remap，绝不把顺序问题带进控制器。
- **限幅**：位置限位、速度限位、加速度/jerk 限位；接近限位时把残差投影到可行方向，不硬顶。
- **柔顺**：接触阶段降低 `K_p`、增大阻尼、限制 `Δq_geo` 幅值；插入阶段用“小步 + 力/位混合”策略：先对准，再小幅推进，检测卡住则回退/微调。
- **奇异点**：阻尼最小二乘 + 条件数监控；接近奇异时冻结腕部残差，改用关节空间小步。
- **抓取/释放**：夹爪开度 + EE 位姿 + 物体位姿做谓词；释放前用 SVL 检查物体是否在目标位姿的容差内。
- **不覆盖 VLA**：JRS 是“残差”不是“替代”；`α` 随置信度自适应，位姿无效时 `α=0`，退回 VLA 原动作。

**伪代码**：

```python
def jrs_step(q, dq_vla, T_target, T_current, pose_valid, cfg):
    if not pose_valid:
        return clip_smooth(dq_vla, q, cfg)
    e = se3_log(T_target @ inv(T_current))
    J = geometric_jacobian(q, ee_frame="dex1_base")
    dq_geo = damped_pinv(J, cfg.lambda_) @ (cfg.Kp * e + cfg.Kd * e_vel)
    alpha = cfg.alpha_max * pose_confidence
    dq = dq_vla + alpha * dq_geo
    dq = clip_velocity(dq, cfg.v_max, cfg.dt)
    dq = clip_position(q, dq, cfg.q_min, cfg.q_max)
    dq = jerk_limit(dq, cfg.jerk_max, cfg.prev_dq)
    return dq
```

**与动作空间研究的关系**：VLA 负责 joint delta 的“学习部分”，JRS 负责“度量修正部分”；两者都在关节空间，避免 EE absolute 的 IK 奇异/误差累积，同时获得 task-space 的闭环精度。

### 3.5 与 SSG/PGL/OPT/ICR/SVL/NRB 的整合

- **SSG**：官方 32 任务步骤/权重 → 状态机；每一步有进入谓词、完成谓词、超时/重试。PCH 的 step head 提供语义先验，SSG 提供硬约束。
- **PGL**：目标从“槽位/2D 锚点”升级为“6D 位姿 + 容差”；MPG 给当前 6D，PGL 给目标 6D；两者相减就是 JRS 的 `e_pose`。
- **OPT**：K 条演示的“容器系释放位姿”中位数/离散度 → 目标先验因子；离散度大时放宽容差、降低 `K_p`，离散度小时收紧。
- **ICR**：关系中心键（物体-容器相对位姿、相位、EE 速度、光流）检索 K 条演示；检索结果只作为先验/上下文，不直接复制动作。
- **SVL**：释放后等 0.3–0.5s，检查物体位姿是否稳定在目标容差内；若掉落/歪斜，PPR 触发重抓/重放。
- **PPR**：位姿谓词包括 `grasped`（物体随夹爪移动）、`placed`（物体在目标容差内且稳定）、`inserted`（插入深度/相对位姿）、`closed`（拉链/盒盖闭合）、`upright`（直立）。谓词失败 → 恢复策略。
- **NRB**：官方 human 备注（先叠后撤、拉链拉开、拧回瓶盖、移动目标等）→ 训练时的破坏-恢复对；推理时用 PPR 检测同类失败，调用对应恢复原语。

### 3.6 SCT：仿真标定孪生

**三件事**：

1. **标定**：
   - 头部相机：用 `state_d435` + `T_base_torso × d435_joint` 固定 D435 外参；优化 `head_stereo` 相对 D435 的外参、内参/畸变/双目基线，使已知点（EE、桌面角点、标定板）重投影误差最小；
   - 腕部相机：用官方仿真挂点做初值，用数据集/真机手眼标定 refine；
   - 桌面平面/高度：用点云 RANSAC + EE 抓取高度估计；
   - 关节零位/符号/限位：用 FK 与 `state_torso`/EE 对照，确认 URDF 顺序。
2. **位姿标签**：
   - 在孪生中渲染物体/容器在已知 6D 位姿下的图像，生成 PCH 的监督；
   - 用 SAM 3D 从真实首帧重建物体网格，导入孪生；
   - 用 FoundationPose 在真实帧上做离线 6D 跟踪，生成伪标签；
   - 用重投影/时序一致/多视角一致做质检。
3. **5 轴反事实**：
   - 位置：物体/容器平移/旋转；
   - 干扰物：加入官方备注里的干扰物；
   - 背景：换桌面纹理/光照/背景板；
   - 未见物品：替换物体网格/颜色/尺寸；
   - 人为干扰：按官方 `human_1_note`/`human_4_note` 脚本移动/撤销；
   - 渲染成对观测/动作，用于 PCH/JRS/SVL 的鲁棒性训练。
4. **伺服验证**：
   - 在孪生中跑 JRS，检查关节限位、碰撞、奇异点、时序；
   - 用 domain randomization 调 `K_p/K_d/α/限幅`，再上真机调试槽。

### 3.7 KSI：运动学接口自检

**离线审计**（一次性）：

1. 用官方 URDF 计算 `torso_link`、`d435_link`、`left_dex1_base_link` 的 FK；
2. 与数据集 `state_torso`、`state_d435`、`left_ee_pose_gripper_base` 对比；
3. 确认关节顺序、符号、零位、EE 偏移；
4. 把结果写进 `calib.json`，训练/推理共用。

**在线审计**（调试槽/运行时）：

1. 发一个小角度探测（例如腕部 roll +0.05 rad，保持其他关节），观察 `left_ee_pose_gripper_base` 的变化方向；
2. 若观测到的旋转轴与命令不符，判定顺序/符号错误，自动 remap；
3. 运行时被动检测：比较“命令的关节增量”与“观测的关节增量/EE 变化”，若长期不一致，降低 `α` 并告警；
4. 相机外参自检：用 `state_d435` 与图像中的已知点（桌面/EE）做重投影，若误差突增，标记相机异常。

**产出**：`calib.json` + `joint_order_map` + `camera_extrinsics` + `ee_offset`；这是零成本的“防翻车”层。

### 3.8 SRL：交互可信度护盾

平台会记录每次 `get_action` 的延迟和动作内容，异常 outlier 会影响结果可信度。SRL 做四件事：

- **延迟稳定**：固定推理路径，避免可变长度 reasoning；位姿头/动作头并行；缓存视觉 token；目标 P99 < 200ms。
- **动作规整**：限制 chunk 内/ chunk 间的 jerk、速度、加速度；禁止 NaN/Inf/超限；对离群维度做中值/低通滤波。
- **chunk 衔接**：用重叠混合（前 20% 平滑过渡）避免 chunk 边界跳变。
- **健康检查**：token、shape、dtype、时间轴、关节顺序、夹爪范围；失败时返回安全保持动作，不返回异常。

### 3.9 与 VLA 基座的接口

**候选基座**：

| 基座 | 规模 | 优点 | 风险 | 建议 |
|---|---:|---|---|---|
| WLA-1.0-Base [S25] | 6B | 官方 UnifoLM、Apache-2.0、24GB 可微调、与赛事生态近 | 6B 推理延迟；需验证 G1 动作头 | 默认，延续第 5–7 轮 |
| MolmoAct2 [S37] | 4B/7B | 3D/depth 推理强、开源、LeRobot 集成 | batch 执行不重规划；需改 joint 头 | 备选/位姿头参考 |
| DM0 [S41] | 2.4B | 2.4B、joint/全身、空间 CoT、62% 专家 | 需适配 G1/Dex1；bbox 粗 | 算力受限时的首选 |

**接口**：

```python

model = MetricPilot.from_pretrained(base_ckpt, pose_head_ckpt)
out = model(images, language, proprio)
# out.action: (T, 14) joint delta + gripper + pivot
# out.pose:   object/container/gripper 6D + confidence

```

**动作维度**：左臂 7 + 右臂 7 + 左夹爪 1 + 右夹爪 1 + pivot 7（可选）。`control_space="joint"`；`action_chunk_size` 建议 8–16（30Hz 下 0.27–0.53s），异步推理 + SRL 平滑。

## 4. 数据引擎

### 4.1 官方数据

- 32 数据集、约 33k episodes/169h；HangCup 1,043 条/194,564 帧/30fps；4 RGB 640×480；无 depth；每任务 5 条英文复述（32×5=160）。
- 字段：双臂 7、夹爪 1、`lower_body` 15、legs 6+6、EE base/torso 6、`state_torso` 6、`state_d435` 6、`waist_state_joint` 3、`recomputed_ee_valid`；action 含 joint/EE/gripper/pivot。
- 用途：VLA 动作头微调、PCH 的 EE/相机/关节标签、SSG 的步骤/语言、SVL 的成功/失败片段。

### 4.2 仿真数据

- 官方 G1+Dex1 资产、相机配置、URDF；Isaac Lab/MuJoCo。
- 生成：PCH 位姿标签、5 轴反事实、JRS 伺服验证、相机/桌面标定。
- 规模：5–8 个孪生任务 × 每任务 2k–5k 帧 × 5 轴变体；总量 50k–200k 帧，远小于全任务孪生。
- 质检：渲染与真实首帧的 SSIM/关键点重投影/相机位姿一致；不追求 photorealism，追求几何/位姿正确。

### 4.3 自采数据（可选）

- 伙伴实验室（有 G1 的高校/产业学院）按统一协议采集 1–2 个任务 × 100–200 条，重点补背景/位置轴。
- 合规开关：默认 C1（不并入训练）；若规则允许（C2），再用。
- 采集协议：固定相机/桌面/光照记录；每场景 3 个位置 × 3 个背景 × 2 个干扰物；带 EE/关节/相机位姿。

### 4.4 标签与质检

| 标签 | 来源 | 质检 |
|---|---|---|
| EE/相机/躯干位姿 | 官方数据 | 与 URDF FK 逐位对比；`recomputed_ee_valid` |
| 物体/容器 6D | SCT 渲染 / SAM 3D + FoundationPose | 重投影 <5px；时序一致；多视角一致 |
| 关键点/2D 锚点 | 人工/SAM/仿真 | 可见性/遮挡标记；重投影 |
| 步骤/谓词 | 官方 score_steps + 人工 | 与视频对齐；边界帧复核 |
| 成功/失败 | 官方 episode 结束 + SVL | 失败原因分类；恢复片段配对 |
| 深度 | 双目/DA3/PCH | 尺度锚定（桌面/EE）；异常剔除 |

### 4.5 数据混合与课程

- 动作头：官方真实 70% + 仿真 20% + 自采 10%（若允许）；frame-wise 空间随机化。
- 位姿头：仿真 50% + 真实伪标签 40% + 真实精确标签 10%；先仿真预训练，再真实微调。
- 课程：先 Easy（T01/T02/T20/T27）→ Medium（T07/T19/T26/T31）→ Hard（T05/T10/T12/T14/T16/T28/T29）；先刚性物体，后透明/布料/拉链。
- 类别平衡：每任务至少 1k 帧；难任务过采样 2×；失败/恢复片段过采样 2×。

## 5. 训练配方

### 5.1 基座与算力阶梯

| 档位 | 基座 | 训练方式 | 显存 | 时间 | 适用 |
|---|---|---|---:|---:|---|
| 最低 | DM0 2.4B | LoRA + 新头 | 24GB | 1–2 周 | 单卡 4090/A100 |
| 推荐 | WLA-1.0-Base 6B | LoRA/部分解冻 | 24–48GB | 2–3 周 | 1–8×A100 |
| 拉伸 | MolmoAct2 4B/7B | 全量/ LoRA | 40–80GB | 3–4 周 | 8×H100 |

默认推荐档：WLA-1.0-Base + LoRA + 新 action/pose/step 头；若算力不足，降级 DM0 2.4B。

### 5.2 训练阶段

**阶段 0：接口与标定（1–2 天）**

- KSI 离线审计；生成 `calib.json`；
- 数据加载器：4 RGB、语言、proprio、EE/相机位姿、步骤标签；
- 复现基线：VLA-only 在官方数据上的动作 MSE/成功率（仿真）。

**阶段 1：位姿头预热（3–5 天）**

- 冻结 VLA backbone，训练 PCH 的 6D/keypoint/depth 头；
- 数据：仿真 + 真实伪标签；
- 指标：ADD/ADD-S、平移/旋转误差、重投影；
- 门：真实帧 80% 分位 <2cm/10°。

**阶段 2：joint delta 动作头（5–7 天）**

- 在官方数据上微调 action head，joint + chunk-wise delta；
- 损失：flow matching/回归 + 平滑 + 限位；
- 数据：官方 32 任务，按难度/任务平衡；
- 门：动作 MSE 不差于 absolute 基线；无超限/NaN。

**阶段 3：单 checkpoint 多任务联合（5–7 天）**

- 解冻/部分解冻 backbone；action + pose + step + depth 联合；
- 位姿图 token 作为输入（teacher forcing → scheduled sampling）；
- 损失权重：action 1.0、pose 0.3、kp 0.2、step 0.1、consistency 0.1、depth 0.1；
- 门：action 成功率下降 <2pp；PCH 不退化为“只看语言”。

**阶段 4：仿真校准/反事实微调（3–5 天）**

- 用 SCT 的 5 轴反事实 + 官方数据混合；
- frame-wise 空间随机化（相机位姿、桌面高度、物体位置）；
- 门：5 轴 OOD 相对提升 >3pp（仿真）。

**阶段 5：伺服调参（2–3 天）**

- 在孪生中黑盒优化 JRS 的 `K_p/K_d/α/限幅`；
- 真机调试槽微调；
- 门：T01/T10/T27 至少 2/3 任务 +5pp。

### 5.3 损失细节

```text
L_action = flow_matching(Δq, Δq_gt) + λ_smooth ||Δq_t - Δq_{t-1}||²
L_pose = geodesic(R, R_gt) + ||t - t_gt||_1 + λ_sym ADD-S
L_kp = ||π(K, T, kp) - kp_2d||² + λ_depth ||z - z_gt||²
L_step = CE(step) + BCE(predicate)
L_consistency = ||FK(q) - EE||² + ||T_mpg - T_pch||²
L_depth = scale-invariant log depth + gradient
```

### 5.4 超参与算力

- 图像分辨率：训练 448×448 或 512×512；推理按 `image_resize` 可降到 320×320（精度任务保留腕部 448）。
- Batch：动作头 64–128；位姿头 32–64；联合 32–64（梯度累积）。
- 学习率：LoRA 1e-4；新头 3e-4；cosine + warmup。
- 训练时长：推荐档 2–3 周（8×A100）；最低档 1–2 周（1×A100/4090）。
- 数据量：官方 33k episodes；仿真 50k–200k 帧；总样本 1–3M 帧。

### 5.5 延迟优化

- 视觉 token 缓存：同一帧的 backbone 只跑一次，action/pose/step 头共享；
- 位姿头轻量：2–3 层 MLP/Transformer，10–20ms；
- 位姿图：1–3ms；
- JRS：<1ms；
- VLA chunk 8–16，异步推理；P99 目标 <200ms；
- SRL 限制 chunk 边界跳变；避免可变长度 reasoning 导致延迟抖动。

## 6. 实验矩阵

### 6.1 离线指标

| 模块 | 指标 | 目标 |
|---|---|---|
| PCH 6D | ADD/ADD-S、平移/旋转误差、重投影 | 80% 分位 <2cm/10°；中位 <1cm/5° |
| PCH 关键点 | PCK@5px、重投影 | >80% |
| Action | MSE/DTW、平滑度、限位违规 | 不差于基线；0 违规 |
| Step | 准确率/F1 | >85% |
| MPG | 内点率、重投影、时序抖动 | 内点 >50%；抖动 <5mm |
| JRS | 跟踪误差、jerk、超限 | 跟踪 <5mm；0 超限 |
| SCT | 相机重投影、位姿标签一致性 | <5px；>95% 一致 |

### 6.2 仿真评测

- 32 任务 × 5 轴 × 2 trials = 320 trials（相对比较，不作为真机结论）；
- 5–8 个孪生任务 × 5 轴 × 10 trials = 250–400 trials（更细的消融）；
- 指标：成功率、步骤分、时间、恢复率、关节限位/碰撞。

### 6.3 真机调试槽 A/B

| 轮次 | 任务 | 对比 | 样本 | 门 |
|---|---|---|---:|---|
| #1 | T01 HangCup | VLA-only vs +MPG vs +JRS vs +MPG+JRS | 每臂 10 | 至少 2/3 任务 +5pp |
| #2 | T10 PlugCharger | 同上 | 每臂 10 | 插拔 +10pp 或步骤分 +10 |
| #3 | T27 StackBowls | 同上 | 每臂 10 | 堆叠 +10pp |
| #4 | T19 ZipUp / T31 OrganizePencilCase | 最终配方 vs 基线 | 每臂 10 | 至少 1/2 任务 +5pp |

调试槽稀缺：每个大版本最多 1 槽；先 T01/T10/T27，通过后再扩。

### 6.4 全量 320 trials

- 32 任务 × 10 trials；成功率先行，步骤分 tie-break；
- 分层分析：5 轴、Easy/Medium/Hard、刚性/透明/布料/拉链、单臂/双臂；
- 统计：配对设计；报告 95% CI；不承诺 3pp；
- 目标：总体 +7–10pp，或 5–8 个任务 +15–20pp。

### 6.5 消融

| 消融 | 目的 |
|---|---|
| PCH on/off | 位姿头是否伤 action；MPG 是否受益 |
| MPG on/off | 度量闭环的增益 |
| JRS on/off | 关节残差的增益 |
| SCT on/off | 仿真标定/反事实的增益 |
| joint vs EE | 动作空间选择 |
| delta vs absolute | 时间抽象选择 |
| frame-wise vs episode-wise | 空间随机化粒度 |
| 相机外参扰动 | 标定鲁棒性 |
| 关节顺序 remap | 接口风险 |
| 透明/布料 fallback | 失败模式 |

### 6.6 停止条件

- PCH 真实帧 >2cm/10°：停 MPG，退回 2D 锚点；
- JRS 在 T01/T10 上 <5pp：停 JRS，保留 VLA joint；
- SCT OOD <3pp：停数据生成，只保留标定；
- PCH 使 action 下降 >2pp：位姿只离线/申请独立模型；
- 延迟 P99 >300ms：减头/降分辨率/换小基座。

## 8. 风险与合规

### 8.1 单模型合规阶梯

| 级别 | 推理时模型 | 位姿来源 | 合规性 | 默认 |
|---|---|---|---|---|
| C0 | 1 个 VLA | 2D 锚点/自监督位姿头 | 最稳 | fallback |
| C1 | 1 个 VLA（含 pose head） | PCH + 确定性 MPG | 推荐 | **默认** |
| C2 | 1 个 VLA + 官方仿真离线 | PCH + SCT 标签 | 取决于外部数据规则 | 可选 |
| C3 | VLA + 独立位姿模型 | FoundationPose/SAM 3D | 可能违反单模型 | 需书面确认 |

- MPG/JRS/KSI/SRL/SSG 都是确定性代码，不是“模型”；
- SCT/FoundationPose/SAM 3D 只离线打标签，不进推理；
- 若规则把“预训练位姿模型离线使用”也算违规，回退 C0：只用官方数据的 EE/相机位姿 + 2D 锚点 + 自监督。

### 8.2 外部数据/模型

- 默认只用官方 32 数据集 + 官方仿真资产；
- 伙伴实验室自采数据（L2L）挂在 C2 开关后；
- 仿真数据只做预训练/校准，最终在官方数据上微调；
- 若规则禁止外部数据/仿真，回退 C0；
- 所有外部来源在模型卡/提交说明中注明。

### 8.3 技术风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 头部双目内参/基线未知 | 深度尺度错 | 自标定 + 桌面/EE 锚定；失败用单目/腕部 |
| 腕部外参未知 | 局部位姿错 | 官方仿真先验 + 手眼标定 + SCP slack |
| 透明/布料/拉链位姿不可辨识 | PCH 失效 | 2D 锚点/关键点/affordance；SSG/SVL fallback |
| 评测端关节顺序不同 | 腕部动作错 | KSI 探测 + remap |
| 位姿头伤 action | 成功率下降 | 共享 backbone + 小权重 + 门控；位姿只离线 |
| JRS 与 VLA 冲突 | 动作抖动 | 残差限幅 + 置信度门控 + SRL |
| 延迟抖动 | 平台记录异常 | 固定路径 + 缓存 + 异步 + P99 监控 |
| 仿真-真实差距 | 标签/策略迁移差 | 空间校准优先；frame-wise 随机化；真机微调 |
| 调试槽稀缺 | 无法充分 A/B | 每版本 1 槽；优先高价值任务；离线筛选 |

### 8.4 需要向主办方确认的问题

1. 确定性几何算法（双目/ICP/因子图）是否算“模型”？
2. 同一 checkpoint 内的辅助位姿头是否允许？
3. 外部预训练权重（SAM 3D/FoundationPose/Depth Anything）离线打标签是否允许？推理是否允许？
4. 仿真数据能否用于预训练/校准？最终模型是否必须只在官方数据上训练？
5. 伙伴实验室自采数据是否允许？需要什么文档/许可？
6. 单任务调试槽的次数、成本、提前期？
7. 评测端 joint action 的顺序/符号/零位是否有文档？能否提供一次探测接口？
8. 平台是否提供相机内参/基线/腕部外参？如果没有，是否允许我们在调试槽做标定？

### 8.5 安全/可信度

- 所有动作限幅/限速/限 jerk；异常返回保持动作；
- 不执行可能损坏机器人/物体的高风险动作；
- 记录每次推理的输入/输出/延迟，便于复盘；
- 不把未验证的位姿直接用于高速运动；接触阶段降速/柔顺。

## 12. 一句话押注

**UniBot 的 <30% 不是语义不够，而是语义到度量、度量到关节执行之间缺一层；用单 checkpoint 的位姿头 + 确定性度量位姿图 + 关节空间残差伺服，配一个只做标定/反事实的仿真孪生，把通才模型的精度失败转成可恢复的闭环。**
