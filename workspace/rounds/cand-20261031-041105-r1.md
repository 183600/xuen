# 第 1 轮（总第 14 次迭代）· VIGIL：让冻结的 VLA 在推理时“验证着选”，在部署后“审计着学”

> 检索/复核日期：**2026-10-31（UTC）**。本轮是新循环第 1 轮，承接第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。三个灵感词是「持续学习」「论文发表」「迭代验证」。本轮不推倒 CHUNK-SERVO，而是补它没有解决的两个缺口：**30 步 plan 仍是单样本、无法在执行前被验证；失败经验没有被系统地变成下一次可用的记忆。**

## 0. 思考流：CHUNK-SERVO 解决了“执行环”，但没解决“选择环”和“记忆环”

### 0.1 上一轮的真实边界

CHUNK-SERVO 把 30 步开环 chunk 切成 6 个 5 步执行块，用确定性视觉伺服把反馈周期从约 1 s 降到 167 ms 执行块（含 RTT 约 200–320 ms）。它解决的是：

> **给定一个 plan，怎么把最后 3 厘米执行对。**

但它隐含了两个假设：

1. **plan 本身是对的。** VLA 是随机生成模型（扩散/流匹配），同一个观测、不同噪声种子会给出不同 plan；CHUNK-SERVO 只执行其中一次采样。如果这次采样在语义上就错了（抓错物体、绕错方向、顺序错），伺服越忠实，错得越远。
2. **失败只值一次 trial。** 官方 320 trials 的失败经验、单任务通道的失败经验，除了做离线分析，没有进入下一次决策。下一轮还是同一个冻结模型、同一套先验。

所以本轮把控制环往上抬两层：

- **选择环**：在执行前，对 \(K\) 个候选 plan 做一次“无学习权重的验证”，只执行通过验证的那个；验证不过就回退到 CHUNK-SERVO 基线。
- **记忆环**：只把“成功 + 几何合法 + 可复现 + 无安全事件”的经验写进一个持续增长的实例库；它不是第二个模型，是数据。

一句话：**上一轮把执行从开环变成闭环，这一轮把“选哪个 plan”和“记住什么”也变成闭环。**

### 0.2 为什么现在做：2026 年的 test-time scaling 已经证明“多采样”有用，但强验证器几乎都要再训一个模型

截至 2026-10-31 的公开工作（检索见产物区 §11）已经形成一个很清楚的图谱：

- **学出来的验证器效果最好，但代价是第二个模型。** TapSampling 用 Action-VAE 生成候选、再用任务进度验证器打分；VeriVLA 用 JEPA 潜世界模型给候选 chunk 排序；DiVeR 训练决策关键度加权的验证器；UF-OPS 用 rollout 数据训练成功概率验证器；VEGAS 用生成式验证器做 action selection。这些工作在 LIBERO/RoboTwin/真机上都有明显增益，但它们共同的前提是：**可以再训练一个验证器/世界模型**。
- **不训练验证器的方法存在，但大多只利用单模型内部信号。** MG-Select 用“遮蔽状态/语言后的参考分布”做 KL 置信度选择，不需要外部模块；它的优势是合规、轻量，但它不知道接触几何，也不知道伺服还能不能救回来。
- **检索/记忆类方法证明“冻结 VLA + 成功经验”有效。** Retrieval-VLA 用稀疏关键点检索历史 plan；Retrieve-then-Steer 把在线成功经验做成 elite prior，注入 flow sampler；RTCF 用 progress-aligned memory 在 DCT 低频段做残差修正；MemBodied / MEM / Mem4Act 则把记忆做进 VLA 的潜状态或上下文。它们证明：**不更新权重，也能让冻结模型适应。**
- **持续学习 VLA 的主流结论是“预训练 VLA 没那么容易忘，experience replay 很有效”。** 但这仍然需要微调/回放训练，和“单模型、320 trials、远程 API”的竞赛约束不是一回事。

把这三条放在一起，缺口就很清楚：

> **没有人把“无学习验证器 + 选择性风险控制 + 通过审计的持续记忆”做成一个单模型合规的推理时算法。**

学出来的验证器不合法（或至少高风险）；不学的验证器又没有风险保证；检索/记忆方法只把记忆当作条件或修正，没有把“这次到底该不该执行这个候选”变成一个**可校准的统计决策**。

### 0.3 三个灵感词怎么落到可计算对象

| 灵感词 | 本轮的可计算对象 | 不做什么 |
|---|---|---|
| **持续学习** | 增长型实例库 \(\mathcal{M}\)、准入谓词 \(A(e)\)、覆盖半径 \(\epsilon(\mathcal{M})\)、版本化快照；只增数据，不改权重 | 不做在线梯度更新；不做第二个学习策略/残差网络；不把官方评测 trial 偷偷写进共享记忆 |
| **论文发表** | 预注册假设、选择性风险 \(R(\tau)\)/覆盖率 \(C(\tau)\)、效应量与置信区间、消融、负结果、复现包 | 不把预览榜单当证据；不挑任务 cherry-pick；不把 +1–2pp 噪声写成结论 |
| **迭代验证** | 候选生成 → 验证器打分 → 选择性门控 → 执行 → 执行后残差 → 记忆准入 → 发布审计 | 不做无校准的 best-of-N；不做“验证器说好就执行”的黑箱 |

### 0.4 核心赌注

> **VIGIL 的赌注：VLA 仍然是唯一的学习模型；但“从 K 个候选里选哪个”可以由一个无学习权重的验证器 + 一个可校准的选择性风险门控来决定；“下一次用什么经验”可以由一个只收录审计通过的成功实例的库来决定。额外算力不花在再训一个模型，而花在验证候选和审计经验上。**

三个可证伪的创新点：

1. **TV-verifier（training-free verifier）**：用“演示相对轨迹一致性 + 运动学/碰撞可行性 + CHUNK-SERVO 伺服余量 + 候选共识”给 plan 打分；不加载第二个学习模型。用 G0/G2 验证它是否真的和成功相关。
2. **SRC（selective risk control）**：把“执行候选 vs 回退基线”变成选择性预测问题；用 Learn-then-Test / Clopper-Pearson 校准阈值，控制被选中 plan 的失败率 \(\le\alpha\)。用 G1/G4 验证风险-覆盖率曲线。
3. **GIL（growing instance library）**：只收录通过“成功 + 几何合法 + 平滑 + 数字孪生复现 + 无安全事件 + 新颖性”六项审计的 episode；用 k-center 做多样性裁剪；用覆盖半径解释“记忆为什么会让验证器变好”。用 G3/G6 验证持续学习不带来回归。

### 1.3 为什么“选择性风险控制”是正确的问题表述

best-of-\(K\) 的常见做法是“选验证器分数最低的”。问题是：

- 验证器不完美时，best-of-\(K\) 会**放大验证器的偏差**（winner's curse）：K 越大，越容易选到一个“验证器误判为好”的坏 plan。
- 竞赛只有 320 trials，不能靠大量在线试错把偏差平均掉。
- 单模型规则又禁止再训一个验证器来纠偏。

所以正确的目标不是“最大化 best-of-\(K\) 的成功率”，而是：

> **在“被验证器选中的 plan”上，把失败率控制在一个可接受的水平 \(\alpha\)；如果没有任何候选能过这道门，就退回基线，而不是硬执行。**

这就是**选择性预测**（selective prediction）的框架：允许模型弃权（回退），只对“有把握”的样本给出预测；用校准集控制被选中样本的风险。它天然适合竞赛：**宁可回退到 CHUNK-SERVO 的 25–30% 基线，也不要用一个没校准的验证器把 25% 变成 15%。**

## 2. 形式化：VIGIL 到底在优化什么

### 2.1 基础符号

| 符号 | 含义 |
|---|---|
| \(\pi_\theta\) | 冻结的 VLA（唯一学习模型） |
| \(o_t\) | 当前观测（四路 RGB + 本体 + 语言） |
| \(a_{t:t+H}\) | 30 步候选 plan，\(H=30\) |
| \(H_c\) | 执行 chunk，默认 5 |
| \(\mathcal{A}_t=\{a^{(1)},\dots,a^{(K)}\}\) | 候选集合 |
| \(V(a;o_t,\mathcal{M})\) | 无学习验证器分数（越低越好） |
| \(\tau\) | 选择性阈值 |
| \(Y\in\{0,1\}\) | 执行结果（成功/失败） |
| \(R(\tau)\) | 选择性风险 \(P(Y=0\mid V\le\tau)\) |
| \(C(\tau)\) | 覆盖率 \(P(V\le\tau)\) |
| \(\mathcal{M}\) | 增长型实例库 |
| \(e\) | 一条 episode/实例 |
| \(A(e)\) | 准入谓词 |
| \(r\) | 一个待发布的系统配置（release） |
| \(\delta_0\) | 非劣性 margin |

### 2.2 选择性风险控制问题

给定候选集合 \(\mathcal{A}_t\) 和验证器 \(V\)，选择规则是：

\[
\pi_\tau(V)=
\begin{cases}
\text{执行 } \arg\min_{a\in\mathcal{A}_t} V(a), & V_{\min}\le\tau,\\[4pt]
\text{回退到 CHUNK-SERVO 基线}, & V_{\min}>\tau.
\end{cases}
\]

选择性风险与覆盖率：

\[
R(\tau)=P\big(Y=0\mid V_{\min}\le\tau\big),\qquad
C(\tau)=P\big(V_{\min}\le\tau\big).
\]

校准问题：

\[
\tau^\star=\arg\max_{\tau\in\Gamma} C(\tau)
\quad\text{s.t.}\quad R(\tau)\le\alpha,
\]

其中 \(\Gamma\) 是预先登记的候选阈值网格。用 **Learn-then-Test**（LTT）在固定序列上做多重检验，或用 Clopper-Pearson 上界构造保守阈值；在交换性假设下，以至少 \(1-\delta\) 的概率保证 \(R(\tau^\star)\le\alpha\)。

**关键点**：这个保证是**条件于“被选中”**的，不是对回退样本的保证。回退样本的风险就是基线风险；VIGIL 不声称把基线也变好，它只声称“我选中的那些 plan 是经过风险认证的”。

### 2.3 验证器的四个分量

\[
V(a)=\underbrace{w_m V_{\text{mem}}(a)}_{\text{演示相对一致性}}
+\underbrace{w_g V_{\text{goal}}(a)}_{\text{目标相对位姿}}
+\underbrace{w_s V_{\text{servo}}(a)}_{\text{伺服余量}}
+\underbrace{w_c V_{\text{cons}}(a)}_{\text{候选共识}},
\]

硬约束：

\[
V_{\text{geo}}(a)\le\epsilon_{\text{geo}},\qquad
V_{\text{servo}}(a)\le\epsilon_{\text{servo}}.
\]

- **\(V_{\text{mem}}\)**：把候选 EE 轨迹变换到“目标相对系”，与实例库检索出的成功轨迹做 DTW + 末端位姿误差。它回答：“这个 plan 像不像一条成功演示的轨迹？”
- **\(V_{\text{goal}}\)**：候选末端 EE 与 CHUNK-SERVO 的相对目标 \(T_{\text{base},ee}^d\) 的误差。它回答：“这个 plan 的终点是不是接近我们想让夹爪去的地方？”
- **\(V_{\text{servo}}\)**：把候选按 5 步切片，预测 CHUNK-SERVO 在每个块起点的修正量 \(\Delta_b\)；如果修正量很大或连续超限，说明这个 plan 不在伺服的收敛域内。它回答：“就算执行了，伺服救得回来吗？”
- **\(V_{\text{cons}}\)**：K 个候选两两轨迹距离的均值；越接近 medoid 的候选越“合群”。它回答：“模型自己是不是也拿不准？”
- **\(V_{\text{geo}}\)**：FK/IK、关节限位、速度/加速度、工作空间、自碰撞/桌面碰撞、夹爪开度。它回答：“这个 plan 物理上能不能执行？”

**为什么这四个分量是互补的**：\(V_{\text{mem}}\) 管“像不像成功经验”，\(V_{\text{goal}}\) 管“终点对不对”，\(V_{\text{servo}}\) 管“执行层救不救得回来”，\(V_{\text{cons}}\) 管“模型有没有把握”，\(V_{\text{geo}}\) 管“物理上可不可行”。单独任何一个都可以被欺骗；四个一起，才构成一个“执行前的最小审计”。

### 2.4 持续学习：实例库与覆盖半径

实例库：

\[
\mathcal{M}=\{(t_i,\phi_i,\tilde\tau_i,I_i,T_i^{\text{rel}},y_i,w_i)\}_{i=1}^{N},
\]

其中 \(\tilde\tau_i\) 是目标相对系下的 EE 轨迹，\(I_i\) 是腕部/头部关键帧，\(T_i^{\text{rel}}\) 是目标-夹爪相对位姿，\(y_i=1\) 表示审计通过的成功实例，\(w_i\) 是质量权重。

覆盖半径：

\[
\epsilon(\mathcal{M})=\sup_{x\in\mathcal{X}}\min_{m\in\mathcal{M}}d(x,m).
\]

**命题（直觉版）**：若执行一条目标相对轨迹 \(x\) 的成功概率 \(\eta(x)\) 对 \(d\) 是 \(L\)-Lipschitz 的，且 \(\mathcal{M}\) 中存在一条成功轨迹 \(m\) 使 \(d(x,m)\le\epsilon\)，则

\[
\eta(x)\ge 1-L\epsilon.
\]

所以：**记忆越多样、覆盖半径越小，验证器对“这条轨迹会不会成功”的下界就越紧。** 这就是“持续学习”在 VIGIL 里的可计算含义：不是更新权重，而是**用审计通过的成功实例缩小覆盖半径**。

### 2.5 发布审计：论文级的非劣性检验

任何 release \(r\)（新记忆版本、新验证器权重、新伺服增益、新 prompt）都必须在一套**冻结的回归套件**上做配对比较：

\[
H_0:\ \Delta_t\le-\delta_0\quad\text{vs}\quad H_1:\ \Delta_t>-\delta_0,
\]

其中 \(\Delta_t=p_t(r)-p_t(\text{baseline})\)。用预注册的组序贯检验（O'Brien-Fleming 或 e-value）控制族错误率；只有在**目标任务有正向证据**且**所有任务层（尤其 B/C 档）不劣于 \(-\delta_0\)** 时才上线。否则回滚。

这一步是“论文发表”在工程上的对应物：**不是把结果写得好看，而是让“什么算证据、什么时候可以停、失败了怎么报告”在实验前就固定下来。**

## 3. 方法：VIGIL 的三个算法

### 3.1 VIGIL-Select（每个 plan 一次）

```text
输入：观测 o_t，冻结 VLA π，实例库 M，阈值 τ，候选数 K
1. 生成候选 A_t：
   a. 若 π 是随机生成模型：K 个不同噪声种子；
   b. 若 π 是确定性的：在任务相关子空间（横向/接近轴/yaw）做 K 个
      小幅扰动，扰动幅度 ≤ 伺服捕获半径。
2. 对每个 a ∈ A_t：
   a. V_mem  ← 目标相对 DTW + 末端位姿误差（top-k 成功实例）
   b. V_goal ← 末端 EE 与 T_base,ee^d 的误差
   c. V_servo← 5 步切片的预测伺服修正量
   d. V_cons ← 与其余候选的平均轨迹距离
   e. V_geo  ← FK/IK + 关节限位 + 碰撞代理
   f. 硬约束不通过 → 直接淘汰
3. a* ← argmin V(a)
4. 若 V(a*) ≤ τ：返回 a*（交给 CHUNK-SERVO 执行）
   否则：返回候选 0（VLA 默认 plan）或置信度最高的记忆 plan
5. 记录 (V(a*), 是否执行, 结果) 到校准/审计日志
```

### 3.2 VIGIL-Memory（每个 episode 一次）

```text
输入：episode e，结果 y，实例库 M
1. 若 y=0：只存失败签名（任务/相位/相对位姿/失败类型），不存完整轨迹
2. 若 y=1：
   a. GeoOK(e)：无碰撞/限位/超速
   b. Smooth(e)：jerk/加速度在阈值内
   c. ReplayOK(e)：数字孪生同初态回放达到任务或进度阈值
   d. NoSafety(e)：无急停/人碰/异常动作
   e. Novel(e)：与 M 中最近实例距离 > ε
   六项全过 → 加入 M，权重 w_e = 质量 × 置信度
3. 若 |M_t| > N_t：k-center 贪心裁剪，保留覆盖半径最小、最多样的子集
4. 生成版本快照 + 哈希 + 审计日志；reset() 时每端口只读自己的版本
```

### 3.3 VIGIL-Release（每个提交/每轮一次）

```text
输入：候选 release r，冻结回归套件 D_reg，α，δ0
1. 在 D_reg 上做配对：同一初始条件/随机种子，baseline vs r
2. 预注册的组序贯非劣性检验（最多 L 次 look）
3. 目标任务：要求正向证据（Δ > 0 的下置信界 > 0，或达到 MDE）
4. 所有任务层：要求 Δ 的下置信界 > -δ0
5. 延迟/安全：p99 ≤ 预算，无新增安全事件
6. 全过 → 上线；否则回滚；所有结果（含负结果）写入报告
```

### 3.4 与 CHUNK-SERVO 的嵌套关系

```text
VIGIL（plan 层，30 步）
  ├─ 候选生成（K 个 30 步 plan）
  ├─ 无学习验证器（mem/goal/servo/cons/geo）
  ├─ 选择性门控（τ，回退）
  └─ CHUNK-SERVO（执行层，5 步）
        ├─ 视觉伺服（IBVS/PBVS）
        ├─ 接触相位/编辑检测
        └─ 动作适配（WLA 54D → API 21D）
```

- VIGIL 不改变 CHUNK-SERVO 的伺服律；它只决定“执行哪个 30 步 plan”。
- CHUNK-SERVO 的 5 步执行块仍然是反馈周期；VIGIL 的验证发生在 plan 边界（约 1 s），不增加每个 5 步块的延迟。
- 如果 VIGIL 回退，系统等价于 CHUNK-SERVO；这保证了**最坏情况不会比上一轮差**（在动作合法性意义上；成功率仍受验证器/策略影响）。

## 4. 为什么不是已有工作：四个 delta

| 已有路线 | 它们做了什么 | VIGIL 的不同 |
|---|---|---|
| 学验证器（TapSampling/VeriVLA/DiVeR/UF-OPS/VEGAS） | 用额外模型给候选打分 | **不加载第二个学习模型**；验证器是演示几何 + 运动学 + 伺服余量 + 共识的确定性函数 |
| 无验证器选择（MG-Select） | 用同模型内部置信度选候选 | **有接触几何/伺服余量**；并且用**选择性风险控制**校准“什么时候不该选” |
| 检索/记忆（Retrieval-VLA/Retrieve-then-Steer/RTCF） | 检索历史 plan 来条件/修正/引导生成 | 检索用于**验证与准入**，不是直接覆盖动作；记忆只收录**审计通过**的实例；有覆盖半径解释 |
| 持续学习 VLA（ER/PHASER/real-world CL） | 用 replay 微调，避免遗忘 | **不更新权重**；持续学习发生在数据/检索层；无参数遗忘；用发布审计控制行为回归 |

一句话：**别人把额外算力花在“再学一个模型”，VIGIL 把额外算力花在“验证候选 + 审计经验”。**

## 5. 实验与门：先证伪，再提交

### 5.1 门 G0–G7

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | 验证器是否与成功相关？ | A 档任务离线 AUC ≥0.70；组合分数优于单分量 | 只用几何硬约束；关闭软打分 |
| G1 | 选择性风险是否可控？ | 单任务通道上，\(\alpha=0.2\) 时被选中 plan 的失败率 ≤0.2（95% CI），覆盖率 ≥30% | 提高 \(\alpha\) 或降低 K；只保留回退基线 |
| G2 | 是否真的涨点？ | 5 个代表任务中 ≥3 个 +10pp；FoldTowel 不回归 >5pp | 不提交 VIGIL 版本 |
| G3 | 记忆增长是否有益？ | 增长库 vs 静态库：验证器 AUC/覆盖率不降，至少 2/5 任务成功率不降 | 冻结记忆；只做离线分析 |
| G4 | 延迟是否可接受？ | K=4 批处理，p99 ≤150ms；plan 周期 ≤1s | K 降到 2；或只在高风险相位启用 |
| G5 | 单模型是否合规？ | 组件审计：无第二个学习模型；验证器无学习权重；记忆是数据 | 回到 C1（离线标注）或纯 CHUNK-SERVO |
| G6 | 发布是否非劣？ | 冻结回归套件上所有任务层 Δ 的下置信界 > -5pp | 回滚；不提交 |
| G7 | 全量干跑是否稳定？ | N 端口隔离、reset 干净、内存不涨、无超时 | 回退基线 |

### 5.2 合成 sanity check（本轮先做，完整结果在产物区 §6）

在真实机器人之前，先用一个**合成选择性预测实验**验证数学：

- 候选潜质量 \(z_i\sim\mathcal N(0,1)\)，成功率 \(p_i=\sigma(2z_i-0.5)\)；
- 验证器 \(V_i=-z_i+\epsilon_i\)，\(\epsilon_i\sim\mathcal N(0,\sigma_v^2)\)；
- 校准 \(n=500\)，测试 10,000 episodes，50 个校准种子，\(\alpha=0.2,\delta=0.1\)。

结果（详见产物区）：

- 强验证器（\(\sigma_v=0.2\)，AUC≈0.86）：best-of-4 成功率 0.752，校准后 0.718，覆盖率 0.815，选择性风险 0.172；**校准保留了大部分增益，并把风险压在 \(\alpha\) 以下。**
- 中等验证器（\(\sigma_v=0.5\)，AUC≈0.82）：best-of-4 0.721，校准后 0.653，覆盖率 0.666；**风险控制有代价，但仍有 +23pp 相对基线。**
- 弱验证器（\(\sigma_v=2.0\)，AUC≈0.64）：校准几乎全部回退（覆盖率 0.006），成功率回到基线 0.426；**验证器不够强时，选择性门控宁可不用，也不硬选。**
- K=4–8 是甜点；K=16 收益继续涨但延迟不可接受；校准样本 <100 时太保守。

这不是机器人证据，但它证明了一件事：**“验证器强 → 选择性风险控制保留增益；验证器弱 → 自动退化成基线”** 这个安全性质是成立的。真实机器人上的验证器 AUC 是 G0 要回答的问题。

### 5.3 真机单任务协议

- 任务：PlugInEthernet、HangCup、ZipUp、StackBowls、FoldTowel（防回归）。
- 每个任务 5 次 A/B：CHUNK-SERVO baseline vs VIGIL；同一初始条件/随机种子。
- 指标：成功率、步骤分、覆盖率、选择性风险、p99 延迟、回退次数。
- 通过：≥3/5 任务 +10pp，FoldTowel 不回归 >5pp；否则不提交。
- 统计：配对差值 + bootstrap 95% CI；5 次/任务只看方向，不声称显著性。

### 5.4 论文级证据

- **预注册**：假设、任务、指标、α、δ、MDE、停止规则、排除标准。
- **消融**：K、四个验证器分量、校准 on/off、记忆 static/growing、回退 on/off、任务条件门控 on/off。
- **风险-覆盖率曲线**：不是只报一个成功率，而是报“在什么覆盖率下，选择性风险是多少”。
- **负结果**：如果验证器 AUC 不够、覆盖率太低、或涨点不显著，如实报告；这本身是“单模型约束下 test-time scaling 的边界”的有价值结论。

**保留**：

- FACT-VLA 的相位化 BC、CAC 柔顺执行、EGP 证据门控；

**升级**：

- 从“静态演示库”升级到“审计增长实例库”；
- 从“工程门 G0–G7”升级到“预注册的非劣性发布审计”；
- 从“best-of-N 直觉”升级到“选择性风险控制”。

**剪枝**：

- 不做第二个学习验证器/世界模型（单模型风险 + 延迟）；
- 不做在线梯度更新/持续微调（规则风险 + 灾难性遗忘）；
- 不做无校准的 best-of-N（可能放大验证器偏差）；
- 不做官方评测期间的记忆写入（合规风险；默认关闭）；
- 不做 32 任务各一个验证器（过拟合 + 不可维护）。

## 7. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 验证器 AUC 太低 | 覆盖率低，退化成 CHUNK-SERVO + 延迟 | G0 先测；任务条件门控；只保留几何硬约束 |
| 校准分布漂移 | 风险保证失效 | 分层校准；ACI 在线更新（仅测试通道）；保守 margin |
| 记忆污染 | 检索到错误经验 | 六项准入；k-center 多样性；任务/相位过滤；置信度回退 |
| 官方评测期间写记忆 | 规则/公平性风险 | 默认关闭；只在单任务通道/自采数据更新 |
| 延迟超预算 | 评测端记录/超时 | K 自适应；批处理；CPU 验证器；异步 plan |
| 单模型解释 | 被判第二个模型 | 验证器无学习权重；记忆是数据；合规说明 C2 |
| 论文贡献被质疑 | 审稿人说“组合” | 理论（选择性风险 + 覆盖半径）+ 消融 + 预注册 + 负结果 |
| 320 trials 噪声 | 假阳性 | 配对设计；CI；预注册 MDE；聚焦 A 档任务 |

## 8. 一句话押注与本轮最大风险

**一句话押注**：用冻结 VLA 采样 K 个 30 步 plan，用“演示相对轨迹 + 目标相对位姿 + 伺服余量 + 候选共识 + 几何可行”的无学习验证器打分，用选择性风险控制决定“执行还是回退”，用六项审计的成功实例扩充记忆，用预注册的非劣性检验决定是否上线——在不新增学习模型的前提下，把“选 plan”和“记经验”也变成闭环。

**本轮最大风险**：如果验证器与真实成功率的排序相关性不足（AUC 接近 0.5），选择性风险控制会退化成频繁回退，VIGIL 只剩 CHUNK-SERVO 的延迟成本而没有精度收益；这时唯一诚实的结论是“在这个 API/数据条件下，无学习验证器不够用”，而不是继续调阈值。

# 第 1 轮（总第 14 次迭代）产物 · VIGIL 技术报告

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 1 轮（总第 14 次迭代）想法区「VIGIL」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是在它们之上补“plan 选择”和“经验记忆”两层。

## 0. 结论与边界

### 0.1 一句话结论

CHUNK-SERVO 把执行反馈周期从约 1 s 降到 167 ms，但 30 步 plan 仍然是单样本、执行前不可验证、失败经验不进入下一次决策。VIGIL 用冻结 VLA 采样 \(K\) 个 30 步候选，用“演示相对轨迹 + 目标相对位姿 + CHUNK-SERVO 伺服余量 + 候选共识 + 几何可行”的无学习验证器打分，用 **选择性风险控制** 决定“执行还是回退”，用 **六项审计** 只把可信成功经验写进增长型实例库，用 **预注册非劣性检验** 决定是否上线。它不新增任何学习模型，因而在单模型规则下可解释、可复现、可回滚。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、排行榜 JSON 直接核实（沿用第 12 轮，检索日期 2026-10-28） | 规则、API、33,276 eps、WLA `chunk_size=30` |
| B | 我们在公开数据/网页上做的分析，可复现 | 2026 文献图谱、合成选择性预测实验、复杂度推导 |
| C | 设计假设，需 G0–G7 验证 | 验证器 AUC ≥0.70、覆盖率 ≥30%、真机 +10pp |

### 0.3 本轮不做什么

- 不训第二个学习验证器/世界模型/残差策略；验证器是确定性函数。
- 不做在线梯度更新/持续微调；持续学习只发生在数据/检索层。
- 不做无校准的 best-of-\(K\)；没有风险门控就不选。
- 不在官方评测期间把 trial 写进共享记忆（除非规则明确允许）；默认只在单任务通道/自采数据更新。
- 不把预览榜单的任务排名当难度表；不 32 任务各训一个验证器。
- 不假设数字孪生能预测真机绝对成功率；它只做回放准入的**否决项**，不做正向奖励。

| **VIGIL（本轮）** | — | **冻结 VLA 多采样 + 无学习验证器 + 选择性风险控制 + 审计记忆** | **否** | **是** | **审计增长实例库** | **是** |

**缺口**：强验证器几乎都要第二个模型；不学验证器的方法没有风险保证；检索/记忆方法没有把“该不该执行”变成统计决策。VIGIL 的 delta 在这三条的交集。

### 1.3 为什么是“选择性预测”而不是“best-of-N”

best-of-\(K\) 的隐含假设是“验证器分数最低 = 最可能成功”。验证器不完美时，\(K\) 越大越容易选中“验证器误判为好”的坏 plan（winner's curse）。竞赛只有 320 trials，不能靠在线试错平均掉偏差；单模型规则又禁止再训一个验证器来纠偏。

选择性预测的表述是：允许系统**弃权**（回退到 CHUNK-SERVO），只对“有把握”的候选给出执行决策；用校准集控制**被选中候选**的失败率。形式化见 §2.4。它的安全性质正是我们要的：**验证器强 → 保留增益；验证器弱 → 自动退化成基线，而不是硬选。**

### 1.4 未核实/未解决

- 评测端实际控制频率（沿用 30Hz 假设，必须实测）。
- 网络 RTT 分布（同城/跨城/跨洲）。
- 腕部相机内参（数据缺失）。
- 单任务通道可用的 trial 预算（决定校准样本量）。
- 官方 WLA 是否支持批量采样/多噪声种子（决定 K 的实现方式）。
- 官方对“模型”的最宽解释（决定 C2/C3 合规模式）。
- 官方评测期间是否允许在线记忆更新（默认禁止，需邮件确认）。
- 真实验证器 AUC（G0 的核心问题）。

## 2. 问题形式化

### 2.1 符号

| 符号 | 含义 |
|---|---|
| \(\pi_\theta\) | 冻结 VLA，参数 \(\theta\) 不更新 |
| \(o_t\) | 观测（四路 RGB + 本体 + 语言） |
| \(H=30\) | VLA 规划步数 |
| \(H_c=5\) | CHUNK-SERVO 执行块 |
| \(\mathcal{A}_t=\{a^{(1)},\dots,a^{(K)}\}\) | 候选 30 步 plan 集合 |
| \(V(a;o_t,\mathcal{M})\) | 无学习验证器分数（越低越好） |
| \(\tau\) | 选择性阈值 |
| \(Y\in\{0,1\}\) | 执行结果 |
| \(R(\tau)\) | 选择性风险 \(P(Y=0\mid V\le\tau)\) |
| \(C(\tau)\) | 覆盖率 \(P(V\le\tau)\) |
| \(\mathcal{M}\) | 增长型实例库 |
| \(e\) | episode/实例 |

| \(r\) | 待发布配置（release） |

### 2.2 候选生成

**随机生成模型（扩散/流匹配）**：

\[
a^{(i)}\sim\pi_\theta(\cdot\mid o_t),\qquad i=1,\dots,K.
\]

不同噪声种子产生不同 plan；候选共享同一观测，因此结果相关，不是独立同分布。

**确定性模型/固定种子**：在任务相关子空间做小幅扰动：

\[
a^{(i)}=a^{(0)}\oplus\xi_i,\qquad
\xi_i\sim\mathcal{N}(0,\Sigma),\quad
\|\xi_i\|_\infty\le\delta_{\text{pert}},
\]

其中 \(\Sigma\) 只在横向/接近轴/yaw 三个方向有方差，\(\delta_{\text{pert}}\) 取 CHUNK-SERVO 的伺服捕获半径（例如 5 mm / 1°）。候选必须保持在同一个语义模式内；扰动不是“再训一个模型”，是固定分布的动作搜索。

**混合候选**：一半种子、一半扰动；若 VLA server 不支持批量采样，K 顺序调用，并用异步 plan cache 掩盖延迟（见 §5.2）。

### 2.3 验证器

#### 2.3.1 演示相对一致性 \(V_{\text{mem}}\)

把候选 EE 轨迹变换到目标相对系：

\[
\tilde a_j = T_{\text{base,target}}^{-1}T_{\text{base},ee}(a_j).
\]

从实例库检索同任务/同相位的 top-\(k\) 成功轨迹 \(\{\tilde\tau_m\}_{m=1}^{k}\)，定义：

\[
V_{\text{mem}}(a)=\min_{m\le k}\left[
\operatorname{DTW}(\tilde a,\tilde\tau_m)
+\lambda_e\left\|\log\left(T_{\text{ee,end}}^{-1}T_{\text{ee,end}}^{(m)}\right)\right\|
\right],
\]

其中 DTW 距离用平移 + 旋转测地距离：

\[
d(x,y)=\|p_x-p_y\|_2^2+\lambda_R\|\log(R_x^\top R_y)\|_2^2.
\]

DTW 允许时间伸缩，避免“同一动作快慢不同”被误判。若实例库为空或置信度低，\(V_{\text{mem}}=0\) 并打低置信标记。

#### 2.3.2 目标相对位姿 \(V_{\text{goal}}\)

由 CHUNK-SERVO/DG-KEYFRAME 给出当前目标位姿 \(T_{\text{base,target}}(t)\) 和演示检索的相对目标 \(T_{\text{target},ee}^\star\)：

\[
T_{\text{base},ee}^d(t)=T_{\text{base,target}}(t)T_{\text{target},ee}^\star,
\]

\[
V_{\text{goal}}(a)=\left\|\log\left(T_{\text{ee,end}}(a)^{-1}T_{\text{base},ee}^d\right)\right\|_2.
\]

#### 2.3.3 伺服余量 \(V_{\text{servo}}\)

对候选按 5 步切片，在每个块起点 \(b\) 计算 CHUNK-SERVO 的预测修正：

\[
e_b=\log\left(T_{\text{ee}}(b)^{-1}T_{\text{base},ee}^d(b)\right),
\]

\[
\Delta_b=\operatorname{clip}\left(K_p e_b+K_d\dot e_b,\ \pm\delta_p,\ \pm\delta_r\right),
\]

\[
V_{\text{servo}}(a)=\sum_b\|\Delta_b\|_2^2/\sigma_\Delta^2.
\]

若目标位姿有协方差 \(\Sigma_T\)，对 \(T_{\text{base,target}}\) 采样 \(S\) 次取平均（鲁棒版本）。\(\sigma_\Delta\) 由离线标定给出。

#### 2.3.4 候选共识 \(V_{\text{cons}}\)

\[
V_{\text{cons}}(a^{(i)})=\frac{1}{K-1}\sum_{j\ne i}d(a^{(i)},a^{(j)}).
\]

共识低 = 模型自己拿不准；它是**弱信号**，只做 tie-breaker，权重 \(w_c\) 很小。共识也可能偏向“共同的错误模式”，所以不能主导选择。

#### 2.3.5 几何可行性 \(V_{\text{geo}}\)

用 G1 URDF + Dex1 夹爪近似 + 桌面/物体包围盒：

- FK/IK 是否存在解；
- 关节限位、速度/加速度限；
- 工作空间边界；
- 自碰撞/桌面碰撞/物体碰撞（胶囊-球代理）；
- 夹爪开度是否覆盖目标宽度。

\[
V_{\text{geo}}(a)=\sum_j\left[
w_q\phi_q(q_j)+w_v\phi_v(\dot q_j)+w_a\phi_a(\ddot q_j)+w_c\phi_c(q_j)
\right].
\]

硬约束：\(V_{\text{geo}}\le\epsilon_{\text{geo}}\)；不通过直接淘汰。

#### 2.3.6 标量化

\[
V(a)=w_m\tilde V_{\text{mem}}+w_g\tilde V_{\text{goal}}
+w_s\tilde V_{\text{servo}}+w_c\tilde V_{\text{cons}},
\]

其中 \(\tilde V\) 是按任务组标准化的分数（中位数/MAD）。权重在**验证器调参集**上选择（网格/约束优化），**不能**在风险校准集上调；调参集与校准集按 session/物体/背景分组划分，避免泄漏。

### 2.4 选择性风险控制

选择规则：

\[
\pi_\tau(V)=
\begin{cases}
\text{执行 }\arg\min_{a\in\mathcal{A}_t}V(a), & V_{\min}\le\tau,\\
\text{回退到 CHUNK-SERVO 基线}, & V_{\min}>\tau.
\end{cases}
\]

选择性风险/覆盖率：

\[
R(\tau)=P(Y=0\mid V_{\min}\le\tau),\qquad
C(\tau)=P(V_{\min}\le\tau).
\]

校准目标：

\[
\tau^\star=\arg\max_{\tau\in\Gamma}C(\tau)
\quad\text{s.t.}\quad R(\tau)\le\alpha.
\]

**Learn-then-Test（LTT）**：

1. 预注册阈值网格 \(\Gamma=\{\tau_1<\dots<\tau_M\}\)（从保守到激进）。
2. 对每个 \(\tau_j\)，在 calibration set 上计算 \(n_j=\#\{V_i\le\tau_j\}\)、\(f_j=\#\{V_i\le\tau_j,Y_i=0\}\)。
3. 零假设 \(H_j:R(\tau_j)>\alpha\)。p-value：
   \[
   p_j=P_{\text{Bin}(n_j,\alpha)}(\text{failures}\le f_j).
   \]
4. 固定序列检验：从 \(j=1\) 开始，若 \(p_j\le\delta\) 且之前全部拒绝，则拒绝 \(H_j\)；遇到第一个不拒绝就停。选最后一个被拒绝的 \(\tau_j\)。
5. 若没有 \(\tau_j\) 通过，令 \(\tau^\star=-\infty\)（永远回退）。

**保证**：在交换性假设下，固定序列 LTT 控制 FWER；因此以至少 \(1-\delta\) 的概率，选中的 \(\tau^\star\) 满足 \(R(\tau^\star)\le\alpha\)。Clopper-Pearson 上界是等价的保守实现。

**分布漂移**：交换性在真实部署中可能不成立（不同机器人/光照/任务）。用 **Adaptive Conformal Inference（ACI）** 在单任务通道/自采数据上更新阈值：

\[
\tau_{t+1}=\tau_t+\gamma\left(\alpha-\mathbf{1}\{V_t\le\tau_t,\ Y_t=0\}\right),
\]

或对风险估计做指数加权。ACI 控制长期风险，不要求交换性；但它需要在线结果，官方评测期间默认关闭。

**回退的风险**：上述保证只覆盖“被选中”的候选；回退样本的风险是基线风险。整体成功率是
\[
(1-R(\tau))C(\tau)+(1-R_{\text{fallback}})(1-C(\tau)).
\]
VIGIL 不声称把回退也变好；它声称“选中的那些是经过认证的”。

### 2.5 持续记忆与覆盖半径

实例库：

\[
\mathcal{M}=\{(t_i,\phi_i,\tilde\tau_i,I_i,T_i^{\text{rel}},y_i,w_i)\}_{i=1}^{N}.
\]

准入谓词：

\[
A(e)=y_e\land\text{GeoOK}(e)\land\text{Smooth}(e)\land\text{ReplayOK}(e)
\land\text{NoSafety}(e)\land\text{Novel}(e).
\]

覆盖半径：

\[
\epsilon(\mathcal{M})=\sup_{x\in\mathcal{X}}\min_{m\in\mathcal{M}}d(x,m).
\]

**覆盖半径命题**：设执行目标相对轨迹 \(x\) 的成功概率 \(\eta(x)\) 对度量 \(d\) 是 \(L\)-Lipschitz 的；若最近邻 \(m(x)\in\mathcal{M}\) 是成功轨迹（\(\eta(m)=1\)），则

\[
\eta(x)\ge 1-L\,d(x,m(x))\ge 1-L\epsilon(\mathcal{M}).
\]

现实中有执行噪声 \(\xi\)，写成 \(\eta(x)\ge 1-L\epsilon-\xi\)。这个命题是设计 justification，不是严格保证；它说明**记忆多样性（覆盖半径）直接决定验证器的下界**。

**k-center 裁剪**：每个任务保留至多 \(N_t\) 条。目标是最小化覆盖半径：

\[
\min_{S\subseteq\mathcal{M}_t,\ |S|\le N_t}\max_{x\in\mathcal{M}_t}\min_{s\in S}d(x,s).
\]

Gonzalez 贪心（每次选离当前中心集最远的点）给 2-近似；复杂度 \(O(|\mathcal{M}_t|N_t)\)。这是“持续学习”的算法核心：**不是更新权重，而是用有限预算最小化覆盖半径。**

**记忆版本与重校准**：每次记忆更新都会改变验证器分数的分布，因此必须：

1. 递增版本号 + 哈希；
2. 在验证器调参集/校准集上重新校准阈值；
3. 通过发布审计（§2.6）后才能上线；
4. 保留上一版本用于回滚。

### 2.6 发布审计

候选 release \(r\)（新记忆版本/新权重/新伺服增益/新 prompt）在冻结回归套件 \(\mathcal{D}_{\text{reg}}\) 上与 baseline 做配对：

\[
\Delta_t=p_t(r)-p_t(\text{baseline}).
\]

非劣性假设：

\[
H_0:\Delta_t\le-\delta_0\quad\text{vs}\quad H_1:\Delta_t>-\delta_0.
\]

规则：

1. 目标任务：正向证据（\(\Delta>0\) 的下置信界 >0，或达到预注册 MDE）。
2. 所有任务层（A/B/C，5 类泛化轴）：\(\Delta\) 的下置信界 \(>-\delta_0\)。
3. 延迟：p99 不超过预算；无新增安全事件。
4. 组序贯：最多 \(L\) 次 look，O'Brien-Fleming 或 e-value；预注册 \(\alpha,\delta_0,L\)。
5. 全过 → 上线；否则回滚；所有结果（含负结果）写入审计日志/论文表。

## 3. 算法

### 3.1 VIGIL-Select

```python
def vigil_select(obs, vla, memory, tau, K, task, phase):
    # 1. candidate generation
    if vla.is_stochastic:
        A = vla.sample(obs, n=K)                 # K noise seeds
    else:
        A = [perturb(vla.plan(obs), sigma) for _ in range(K)]
    A[0] = vla.default_plan(obs)                  # fallback candidate

    # 2. verifier
    scored = []
    for a in A:
        v_geo = geometry_score(a, obs)             # hard constraint
        if v_geo > EPS_GEO:
            continue
        v_mem = memory_score(a, memory, task, phase)
        v_goal = goal_score(a, obs, memory)
        v_servo = servo_headroom(a, obs, memory)
        v_cons = consensus_score(a, A)
        v = w_m*v_mem + w_g*v_goal + w_s*v_servo + w_c*v_cons
        scored.append((v, a, (v_mem, v_goal, v_servo, v_cons, v_geo)))

    # 3. selective gate
    if not scored:
        return A[0], "fallback_no_feasible"
    v_star, a_star, terms = min(scored, key=lambda z: z[0])
    if v_star <= tau:
        return a_star, "selected"
    return A[0], "fallback_threshold"
```

### 3.2 VIGIL-Memory

```python
def vigil_memory(episode, success, memory):
    if not success:
        memory.add_failure_signature(episode)     # no full trajectory
        return memory
    if not geo_ok(episode): return memory
    if not smooth(episode): return memory
    if not replay_ok(episode, sim): return memory
    if not no_safety_event(episode): return memory
    if not novel(episode, memory): return memory
    memory.add(episode, weight=quality(episode))
    if len(memory[episode.task]) > N_T:
        memory[episode.task] = k_center_greedy(
            memory[episode.task], N_T)
    memory.bump_version()
    memory.snapshot()
    return memory
```

### 3.3 VIGIL-Release

```python
def vigil_release(candidate, baseline, D_reg, alpha, delta0, looks):
    results = []
    for look in looks:
        pairs = paired_rollouts(candidate, baseline, D_reg, n=look)
        d = paired_difference(pairs)             # success diff
        ni_lcb = noninferiority_lcb(d, alpha)     # non-inferiority
        sup_lcb = superiority_lcb(d, alpha)      # superiority
        results.append((look, d, ni_lcb, sup_lcb))
        if ni_lcb <= -delta0:
            return "rollback", results
        if sup_lcb > 0 and look == looks[-1]:
            return "deploy", results
    return "rollback", results
```

### 3.4 与 CHUNK-SERVO/API 的集成

```text
Evaluator (N ports)
  │ websocket: obs / action chunk
  ▼
Per-port PolicyService (CPU)
  ├─ VIGIL-Select (plan level, every ~30 steps)
  │    ├─ candidate cache / K plans
  │    ├─ training-free verifier
  │    └─ selective gate
  ├─ CHUNK-SERVO (execution level, every 5 steps)
  │    ├─ IBVS/PBVS
  │    ├─ contact phase / edit detection
  │    └─ action adapter (WLA 54D → API 21D)
  └─ VIGIL-Memory (between trials, test channel only)
       ├─ admission / k-center
       └─ versioned index
  │
  ▼ async, batched
Shared VLA server (GPU)
  └─ frozen WLA / candidate batch
```

- **VIGIL-Select 在 plan 边界运行**，不增加每个 5 步块的延迟；候选生成异步，plan cache 复用 CHUNK-SERVO。
- **VIGIL-Memory 在 trial 之间运行**；官方评测期间默认关闭写入，只读预加载版本。`reset()` 时每端口恢复到自己的快照。
- **动作适配**沿用第 12 轮：WLA 54D → 2×6 EE + 2×1 gripper + 7 pivot；先 compose 成绝对位姿，再切片；`pivot` 语义未核实前先零回退。

### 3.5 回退与安全

回退顺序：

1. 阈值门控失败 → 候选 0（VLA 默认 plan）+ CHUNK-SERVO。
2. 候选 0 几何不可行 → 记忆库中置信度最高的成功 plan（同任务/相位）。
3. 仍不可行 → 安全 hold（保持当前位置，返回合法零增量 chunk）。
4. 任何异常/NaN/形状错误 → 上一组合法 chunk。

安全约束：

- 每块修正限幅（沿用 CHUNK-SERVO：1 cm / 0.05 rad）。
- 编辑检测触发即停（GEO-RESIDUAL）。
- 最大重试次数；超时进入 hold。
- 不把“验证器通过”当作安全证明；几何硬约束和动作限幅仍然生效。

### 3.6 校准细节

**数据划分**（按 session/物体/背景分组，相邻帧不跨 split）：

- 60% 演示 → 实例库构建；
- 20% 演示 → 验证器调参（权重、标准化参数）；
- 20% 演示 + 单任务通道失败/成功 → 风险校准；
- 单独留出 5 个任务做最终 A/B，不参与任何调参。

**负样本来源**：

1. 单任务通道的真实失败；
2. 数字孪生中对成功演示施加扰动后的失败 rollout；
3. 对成功轨迹做时间/空间扰动，只有数字孪生回放失败才标负；
4. 不用官方评测 trial 做校准（避免泄漏/合规风险）。

**校准流程**：

1. 在调参集上选 \(w_m,w_g,w_s,w_c\) 和标准化参数；
2. 在 calibration set 上计算每个 \(\tau_j\) 的 \(n_j,f_j\)；
3. LTT 固定序列选 \(\tau^\star\)；
4. 在留出任务上测风险-覆盖率曲线；
5. 若覆盖率 <30%，提高 \(\alpha\) 或改进验证器；若风险超 \(\alpha\)，降低 \(\tau\)。

**ACI 模式**：仅在单任务通道/自采数据上启用；每次观测到结果后更新 \(\tau\)；官方评测期间冻结。

### 3.7 记忆索引与版本

- 索引：任务/相位分片；每条存目标相对轨迹、关键帧、相对位姿、质量权重。
- 近邻：小规模用暴力检索（\(N<10^5\)）；大规模用 HNSW/FAISS；CPU。
- 去重：轨迹距离 <\(\epsilon_d\) 视为重复，更新权重/recency。
- 版本：语义版本号 + 内容哈希；每端口只读快照；更新走 copy-on-write。
- 审计：每条准入/拒绝记录原因；可回放“为什么这条进了库”。

## 4. 理论分析

### 4.1 选择性风险控制保证

**命题 1（LTT 风险保证）**：在 calibration 与 deployment episodes 可交换的假设下，按 §2.4 的固定序列 LTT 选择 \(\hat\tau\)，则

\[
P\big(R(\hat\tau)\le\alpha\big)\ge 1-\delta.
\]

**证明 sketch**：每个 \(p_j\) 在 \(H_j\) 下是有效的（二项尾概率）；固定序列检验从保守到激进，遇到第一个不拒绝即停，控制 FWER；被选中的 \(\hat\tau\) 对应最后一个被拒绝的 \(H_j\)，因此其真实风险不超过 \(\alpha\) 的概率至少 \(1-\delta\)。Clopper-Pearson 上界给出等价的保守版本。\(\square\)

**注**：这是**条件于被选中**的风险；回退样本不在保证范围内。若要把回退也纳入，需把回退作为一个固定候选加入校准，或单独报告回退风险。

### 4.2 选择增益的条件

**命题 2（best-of-\(K\) 单调性）**：设 \(V_{(1)}=\min_i V_i\)，\(p(v)=P(Y=1\mid V=v)\) 对 \(v\) 非增。则

\[
P_K=\int p(v)\,dF_{V_{(1)}}(v)
\]

对 \(K\) 非减；若 \(p\) 在正测度集上严格递减，则 \(P_K>P_1\)。

**证明 sketch**：\(F_{V_{(1)}}^K(v)=1-(1-F_V(v))^K\)；\(K\) 增大时分布随机占优（更小的 \(V\)）；\(p\) 非增，积分不减。\(\square\)

**注**：这假设候选在给定 \(V\) 下条件独立；实际候选共享观测，结果相关，增益会小于独立情形。验证器的**单调性/AUC**是核心；若 AUC≤0.5，选择可能有害，选择性门控通过回退保护。这就是为什么 G0 必须先测 AUC。

### 4.3 记忆覆盖半径

**命题 3（覆盖半径下界）**：设 \(\eta\) 是 \(L\)-Lipschitz，\(\mathcal{M}\) 中最近邻 \(m(x)\) 成功。则

\[
\eta(x)\ge 1-L\,\epsilon(\mathcal{M}).
\]

**证明**：\(\eta(x)\ge\eta(m)-L d(x,m)=1-Ld(x,m)\ge1-L\epsilon\)。\(\square\)

**注**：这是理想化；真实执行有噪声，且“成功演示”不保证每次成功。它解释为什么 k-center 多样性裁剪有意义：固定预算下最小化 \(\epsilon\)，下界最紧。Gonzalez 贪心给 2-近似（Gonzalez 1985）。

### 4.4 无参数遗忘

**命题 4（参数空间零遗忘）**：VIGIL 不更新 \(\theta\)；因此对任意旧任务 \(t\)，\(\pi_\theta(\cdot\mid t)\) 的参数不变，参数空间遗忘为 0。

**注**：行为仍可能因记忆检索而改变；这是“检索干扰”，不是“参数遗忘”。控制手段：任务/相位过滤、置信度门控、选择性风险控制、发布审计。每次记忆版本更新都要重新校准。

### 4.5 发布非劣性

**命题 5（组序贯非劣性）**：在预注册的组序贯设计下，若候选通过非劣性检验，则真实 \(\Delta_t\le-\delta_0\) 的概率不超过 \(\alpha\)。这是标准组序贯性质；不赘述证明。

### 4.6 复杂度

| 步骤 | 复杂度 | 说明 |
|---|---|---|
| 候选生成 | \(O(KC_{\text{VLA}})\) | 批处理时墙钟接近 \(O(C_{\text{VLA}})\) |
| \(V_{\text{mem}}\) | \(O(K k H^2)\) | DTW；可用下界/重采样降到 \(O(KkH)\) |
| \(V_{\text{goal}}\) | \(O(KH)\) | 矩阵对数 |

## 5. 系统设计

### 5.1 进程/端口拓扑

- 每个端口一个 `PolicyService`：独立 `reset()`、独立 plan cache、独立记忆快照、独立校准阈值。
- 共享只读：VLA server、实例库基座（copy-on-write）、验证器代码/权重（确定性参数）。
- 任何端口异常不影响其他端口；日志带 `port_id`、`trial_id`、`task_id`、`memory_version`。

### 5.2 延迟预算

| 阶段 | 预算 | 备注 |
|---|---:|---|
| VLA 单候选 | 200–300 ms | 6B，4 步去噪，GPU |
| K=4 批处理 | 300–500 ms | 需 server 支持 batch；否则 K=2 顺序 |
| 验证器 | 10–20 ms | CPU，NumPy/C++ |
| 伺服（每 5 步块） | <5 ms | CPU |
| 计划周期 | 1 s（30 步 @30Hz） | 异步；plan cache 覆盖 |
| `get_action` p99 | ≤150 ms | 返回 5 步 chunk，不等 VLA |
| 冷启动 | ≤1 s | 同步 VLA + 安全 hold |

**关键**：VLA 推理在后台；`get_action` 只做伺服/适配，因此 p99 不受 K 影响。若 server 不支持 batch，K=4 顺序推理会超过 1 s，此时用 K=2 或跨 plan 周期预取。

- `t`、`port`、`task`、`phase`、`memory_version`、`calibration_version`；
- K 个候选的 \(V_{\text{mem}},V_{\text{goal}},V_{\text{servo}},V_{\text{cons}},V_{\text{geo}}\)；
- 选中/回退、阈值 \(\tau\)、延迟；
- 执行结果（若可得）；
- 动作统计（均值/方差/限幅触发）。

审计日志用哈希链；每次 release 记录代码/数据/阈值哈希。这样论文的每个数字都能追溯到一次运行。

## 6. 实验设计与结果

### 6.1 合成 sanity check：选择性风险控制的数学是否成立

**目的**：在真实机器人之前，验证“验证器强 → 保留增益；验证器弱 → 自动回退”的安全性质。不是机器人证据。

**模型**：

- 每个 episode 有 K 个候选，潜质量 \(z_i\sim\mathcal{N}(0,1)\)；
- 成功率 \(p_i=\sigma(2z_i-0.5)\)；
- 验证器 \(V_i=-z_i+\epsilon_i\)，\(\epsilon_i\sim\mathcal{N}(0,\sigma_v^2)\)；
- 校准 \(n=500\)，测试 10,000 episodes，50 个校准种子，\(\alpha=0.2,\delta=0.1\)；
- LTT 固定序列 + Clopper-Pearson 上界；
- 回退执行候选 0（默认 plan）。

**核心代码（可复现）**：

```python
z = rng.normal(size=(n, K))
y = (rng.random((n, K)) < sigmoid(2*z - 0.5)).astype(int)
v = -z + rng.normal(scale=sigma_v, size=(n, K))
j = v.argmin(axis=1)
V_sel, Y_sel = v[np.arange(n), j], y[np.arange(n), j]
# LTT: choose largest tau with CP upper bound <= alpha
# test: execute argmin V if V <= tau, else candidate 0
```

**结果 1：验证器强度 vs 选择性风险控制**（K=4，n_cal=500，50 seeds）

| \(\sigma_v\) | AUC | baseline | best-of-4 | calibrated | coverage | selective risk | guarantee ok |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 0.2 | 0.860 | 0.424 | 0.752 | 0.718 | 0.815 | 0.172 | 1.00 |
| 0.5 | 0.823 | 0.425 | 0.721 | 0.653 | 0.666 | 0.172 | 0.86 |
| 1.0 | 0.743 | 0.425 | 0.652 | 0.501 | 0.243 | 0.149 | 0.84 |
| 2.0 | 0.638 | 0.424 | 0.566 | 0.426 | 0.006 | 0.021 | 0.92 |

- 强验证器（AUC 0.86）：best-of-4 0.752，校准后 0.718，覆盖率 0.815，选择性风险 0.172；**校准保留大部分增益**。
- 中等验证器（AUC 0.82）：best-of-4 0.721，校准后 0.653，覆盖率 0.666；**风险控制有代价，但仍 +23pp 相对基线**。
- 弱验证器（AUC 0.64）：校准几乎全部回退（覆盖率 0.006），成功率回到基线 0.426；**验证器不够强时，宁可不用**。
- `guarantee ok` 是 50 个校准种子中测试选择性风险 ≤\(\alpha\) 的比例，约 0.84–1.00，与 \(1-\delta=0.9\) 的有限样本波动一致。覆盖率极低（如 \(\sigma_v=2.0\) 的 0.006）时，选择性风险的点估计不稳定；此时应看覆盖率/回退率，而不是把 0.021 当成精确风险。

**结果 2：K 扫描**（\(\sigma_v=0.5\)，n_cal=500）

| K | baseline | best-of-K | calibrated | coverage | selective risk | guarantee ok |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 0.425 | 0.425 | 0.425 | 0.165 | 0.141 | 0.88 |
| 2 | 0.426 | 0.583 | 0.505 | 0.339 | 0.153 | 0.94 |
| 4 | 0.425 | 0.721 | 0.653 | 0.666 | 0.172 | 0.86 |
| 8 | 0.424 | 0.822 | 0.815 | 0.972 | 0.170 | 1.00 |
| 16 | 0.425 | 0.890 | 0.890 | 0.999 | 0.110 | 1.00 |

合成里 K=8 更好；真机受 1 s 计划周期限制，默认 K=4，只有批处理/预取可行时才用 K=8；K=16 延迟不可接受。K=1 时校准只会降低覆盖率，没有选择增益（符合预期）。

**结果 3：校准样本量**（\(\sigma_v=0.5\)，K=4）

| n_cal | calibrated | coverage | selective risk | guarantee ok |
|---:|---:|---:|---:|---:|
| 50 | 0.464 | 0.121 | 0.032 | 0.90 |
| 100 | 0.605 | 0.522 | 0.137 | 0.88 |
| 200 | 0.615 | 0.548 | 0.145 | 0.86 |
| 500 | 0.653 | 0.666 | 0.172 | 0.86 |
| 1000 | 0.659 | 0.694 | 0.181 | 0.92 |
| 2000 | 0.664 | 0.709 | 0.184 | 0.86 |

n<100 太保守（覆盖率低）；n=500–2000 稳定。竞赛里校准样本来自单任务通道/仿真；如果只能拿到 50–100 条，必须预期覆盖率低，或改用更简单的几何硬约束。

**结论**：合成实验支持三件事：

1. 选择性风险控制确实能把被选中候选的失败率控制在 \(\alpha\) 附近；
2. 代价是覆盖率/回退；验证器越强，代价越小；
3. 验证器弱时算法自动退化到基线，不会“越选越差”。

**最大的未知**：真实机器人上验证器的 AUC 是多少。这是 G0，不是合成实验能回答的。

### 6.7 统计与功效

- 320 trials，\(p\approx0.25\) 时全局 SE≈2.4pp；不要声称 +1–2pp 是结论。
- 单任务 10 trials 的成功率只能是 0/10…10/10；per-task 效应很噪。
- 主分析：A 档任务的**配对 pooled 差值**；次要分析：5 类泛化轴；安全性：碰撞/超时。
- 预注册 MDE：例如 A 档 pooled +10pp；如果实际效应更小，报告 CI，不硬说显著。
- 用 bootstrap/permutation；报告风险-覆盖率曲线，不只报一个点。

### 6.8 判定与负结果

| 结果 | 解释 | 行动 |
|---|---|---|
| AUC≥0.7，覆盖率≥30%，A/B +10pp | 验证器有效 | 进入全量 |
| AUC≥0.7，覆盖率<30% | 验证器有效但太保守 | 提高 \(\alpha\)、增加校准样本、改进阈值 |
| AUC<0.7，覆盖率低 | 验证器不够强 | 只用几何硬约束；不提交 VIGIL |
| A/B 不涨或回归 | 选择没有转化为成功 | 回滚；分析失败模式 |
| 延迟超预算 | K/验证器太重 | 降 K；只在高风险相位启用 |
| 记忆增长带来回归 | 检索干扰/污染 | 冻结记忆；加强准入/多样性 |

| 风险 | 影响 | 缓解 |
|---|---|---|
| 验证器 AUC 太低 | 覆盖率低，退化成 CHUNK-SERVO + 延迟 | G0 先测；任务条件门控；只保留几何硬约束 |
| 校准分布漂移 | 风险保证失效 | 分层校准；ACI（仅测试通道）；保守 margin；定期重校准 |
| 记忆污染 | 检索到错误经验 | 六项准入；k-center 多样性；任务/相位过滤；置信度回退 |
| 官方评测期间写记忆 | 规则/公平性风险 | 默认关闭；只读快照；需官方确认 |
| 记忆版本改变分数分布 | 旧阈值失效 | 每次更新重校准 + 发布审计 |
| 延迟超预算 | 评测端记录/超时 | K 自适应；批处理；CPU 验证器；异步 plan |
| 单模型解释 | 被判第二个模型 | 验证器无学习权重；记忆是数据；合规说明 |
| 回退风险高于 \(\alpha\) | 整体成功率被回退拖累 | 回退只回基线；报告分解；不声称整体风险 ≤\(\alpha\) |
| 论文贡献被质疑 | 审稿人 | 理论 + 消融 + 预注册 + 负结果 |
| 320 trials 噪声 | 假阳性 | 配对；CI；预注册 MDE；A 档 pooled |

### 8.2 合规模式（沿用第 12 轮）

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 验证器/记忆只离线生成标签；线上只有 VLA | 最低 | 保守 |
| C2 确定性控制器 | 验证器/伺服是几何/统计，无学习权重；VLA 唯一学习模型 | 低 | **主推** |
| C3 同 checkpoint 特征 | 描述子用 VLA 同一 checkpoint encoder，不加载第二个模型 | 低–中 | 需要强描述子时 |

**禁止**：第二个学习策略/残差网络/独立视觉编码器做在线决策；官方评测期间的跨 trial 在线学习（除非规则明确允许）。

### 8.3 失败模式分诊

| 失败模式 | 典型任务 | VIGIL 该做什么 | 不该做什么 |
|---|---|---|---|
| 接触/插入/挂/叠/拉链/锁 | PlugInEthernet、HangCup、ZipUp、StackBowls、Unlock | 验证器 + 选择性门控 + CHUNK-SERVO | 更大 VLA、更多语义数据 |
| 位置/人为干扰 | 5 类泛化轴；human_1/4 | 相对目标 + 记忆 + 回退 | 固定轨迹、开环 chunk |
| 背景/干扰物/未见物品 | FruitSorting、ColorArrangement、OrganizeTools | VLA 微调 + 局部 ROI | 纯几何验证器 |
| 变形/语义/长程 | FoldTowel、PackBag、SpellRobot、ConveyorSorting | VLA 基座 + 任务数据 | 6D 物体位姿网络 |

## 11. 一句话押注

**用冻结 VLA 采样 K 个 30 步 plan，用“演示相对轨迹 + 目标相对位姿 + 伺服余量 + 候选共识 + 几何可行”的无学习验证器打分，用选择性风险控制决定“执行还是回退”，用六项审计的成功实例扩充记忆，用预注册的非劣性检验决定是否上线——在不新增学习模型的前提下，把“选 plan”和“记经验”也变成闭环。**

**本轮最大风险**：如果真实机器人上的验证器 AUC 接近 0.5，选择性风险控制会退化成频繁回退，VIGIL 只剩 CHUNK-SERVO 的延迟成本而没有精度收益；这时唯一诚实的结论是“在这个 API/数据条件下，无学习验证器不够用”，而不是继续调阈值。
