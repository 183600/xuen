# 第 70 轮（承接第 69 轮「FLUID-RAS 交互消歧闭环」IP-253~263；灵感循环新循环第 3 轮；本轮灵感：「价值对齐」×「用户需求分析」）

> R69 问「我该向谁求证、还能问什么」，把不确定性拆成 (U_ale, U_epi)，用流匹配多模态策略 + 主动交互去消解 epistemic。但它默认了三件事：
> - **目标已知**：VoI 衡量的是「哪个动作模态更符合任务」，而不是「这个任务本身是否值得做、为谁做」；
> - **请求即需求**：`g_ask` 问的是事实，回答被当作关于世界的证据，而不是关于「用户真正需要什么」的证据；
> - **提问中立**：问句只是观测通道，不会改变被问者的偏好。
>
> 价值对齐与用户需求分析正好拆掉这三个默认：
> - **价值对齐**说：目标不是单点标量，而是多个利益相关者的、可冲突的、部分不可通约的价值分布；对齐不是「让用户当场满意」，而是「执行的目标能追溯到合法来源、不越过硬约束、且不被提问本身制造」。
> - **用户需求分析**说：请求是需求的**证据**而非需求本身；需求是潜在的、分层的、常常无法被用户直接说清；正确的动作常常不是追问，而是**给选项、做原型，甚至把决定交还**。
>
> 核心命题：**在 (U_ale, U_epi) 之外补上价值侧与需求侧的两种不确定性 U_val、U_need，并各按方差分解为「不可约的合法分歧/异质性（aleatoric）」与「可约的认知不足（epistemic）」；epistemic 用非扭曲 elicitation 与需求验证消解，aleatoric 不标量化、只给菜单或延迟给有授权的人；同时证明 R69 的 λ_floor 对「目标错误」这一风险根本无界，必须换成来源授权 + 二维风险包络 + 一等公民的 defer/menu。** 命名 **WORTH-RAS**（Whose Objective, Revelation-robust elicitation, Trade-off Honest, need Hierarchy）。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「测量准吗」，R69 问「向谁求证、还能问什么」，R70 问「**这件事值不值得做、是为谁做、用户说的就是他真正需要的吗**」——不确定性不只关于世界与动作，也关于目标本身。

## 0. 直觉与动机

**灵感 1（价值对齐 → 目标是带来源的分布，不是匿名标量）**
直觉：把「用户满意」当标量的系统，最容易学会的是迎合而不是对齐。价值对齐的对象不是一个匿名 reward，而是一个三元组：**谁的价值**（provenance）、**哪种价值**（耐久价值 vs 瞬时状态）、**冲突时按什么规则裁决**（aggregation）。两个室友对温度有稳定分歧时，再问一百次也问不出一个「正确温度」；把它平均成一个数，是用算术伪装的政治决定。因此系统必须保留来源与多元性，而不是把分歧当噪声抹平。

形式化直觉：把每个利益相关者的价值参数 θ_i 看成潜变量；总不确定性可做方差分解——组内（同一人、证据不足）是 epistemic，组间（不同人、稳定分歧）是 aleatoric。前者可问，后者不可问；后者只能走合法聚合或菜单。

**灵感 2（用户需求分析 → 请求是需求的证据）**
直觉：用户说「把灯打开」，真实需求可能是「看书不刺眼」。请求 r 是一个**候选解**，不是需求 n* 本身。用户往往说不清需求（尤其创新性需求），但看到选项、摸到原型就能选。于是「问」不只是提问，还包括**给菜单、做原型、让对方选**；有时最安全的动作是**把决定交还**。直接执行 r 可能「技术正确、需求错误」。

**灵感 3（不确定性再分解 → R69 是单利益相关者的退化）**
直觉：R69 把世界侧不确定性拆成 aleatoric/epistemic；价值侧也有同样的结构，但语义不同：价值侧的 aleatoric 不是随机噪声，而是**合法的多元**。把 U_val、U_need 各自再拆，就得到一个四通道处置表：可约的价值/需求 → 非扭曲 elicitation；不可约的价值/需求 → 菜单/延迟；世界侧仍走 R69。R69 恰好是 |S|=1、θ 为点质量、需求图退化为 r=n* 的边界。

**灵感 4（VoI 的阴暗面 → 提问会制造答案）**
直觉：R69 默认「问」只增加信息。但问句是干预：引导性措辞、锚定、社会压力、模型的谄媚，都会改变被问者的报告偏好。若目标函数是「让用户说 yes」，最优问句就是最能制造同意的问句——这不是对齐，是对人的 reward hacking。需要 **revelation-robust VoI**：从信息增益里扣除偏好扭曲，给扭曲设硬上限，禁止针对脆弱性，并要求框架不变性。对齐的度量必须是「稳定偏好」而不是「当场顺从」。

**灵感 5（λ 的盲点 → 目标风险不可收缩）**
直觉：R68/R69 的安全原语是「不确定就把动作缩小/放慢」。这对执行风险有效；但如果目标本身错了，把错事做得更慢、更小，仍然是错事，甚至因为错过时机而更糟。目标风险对动作幅值不单调，λ_floor 对它没有上界。因此价值不确定性不能塞进现有 λ 通道，必须引入**来源授权 + 二维风险包络 + 一等的 defer/menu**。这是本轮从「加一层」升级为「换一种安全原语」的地方。

## 1. 形式化定义（增量：定义 310–326）

**定义 310（WORTH-RAS 总览）** WORTH-RAS = (VPM, NHG, VUD, NEL, PAX, ACT, ORA, RAS-WM‡)。五不变式：
(i) **实时流零学习写操作**（继承 R69 定义 293-i）；
(ii) **来源不变式**：执行目标的每个项都有 stakeholder provenance 与 authority signature，匿名效用非法；
(iii) **硬约束不可交易**：H 永不进入任何加权、折中或补偿；
(iv) **非扭曲不变式**：elicitation 的偏好位移 D(q) ≤ ε_manip，且不得针对脆弱性；
(v) **多元性保持**：不可约价值分歧不得被标量化；无合法聚合规则时只允许菜单/延迟/拒绝。

**定义 311（价值对齐）** 给定合法价值后验 P_leg = {p(θ_i|D)}_{i∈S}、硬约束 H、聚合章程 F，执行目标 u_exec 是**对齐的**，当且仅当：
(a) u_exec 的每个项都有 provenance 且通过授权（定义 318）；
(b) u_exec ∈ F(P_leg, H)（若 F 返回集合，则执行任一菜单项还需被授权选择）；
(c) H 从不参与交易；
(d) 形成 P_leg 的 elicitation 满足非扭曲约束（定义 316）。
注意：用户当场说「满意」不在定义内；那只是行为代理，可能是被问句制造出来的。

**定义 312（利益相关者与价值状态）** 有限集 S={1,…,n}，每个 i 有合法性权重 ℓ_i∈[0,1]（不是效用权重）、授权范围 A_i、价值状态 v_i=(θ_i,m_i)，其中 θ_i∈Θ_i 为耐久价值参数、m_i∈M_i 为瞬时状态；u_i: Y×Θ_i→ℝ。Y 为结果特征空间。证据 D 下分别得耐久后验 p(θ_i|D) 与瞬时后验 p(m_i|D)。ℓ_i 只决定「谁有资格进入聚合」，不决定「谁的偏好更重要」。

**定义 313（需求图与请求—需求反演）** 需求图 G_need=(N,E) 是 means-end DAG：根节点 n* 为待完成 job，中间节点为期望结果，叶节点为候选解 s。请求 r 是叶节点 s_r 的观测，观测模型 p(r|s_r)。由贝叶斯反演得 p(n*|r,D) ∝ Σ_s p(r|s)p(s|n*)p(n*|D)。动作 a 诱导结果 y_a，需求满足度 σ(n*,y_a)∈[0,1]。

**定义 314（价值/需求不确定性的方差分解）** 价值侧：
Var(θ) = E_i[Var(θ_i|D)] + Var_i(E[θ_i|D])。
第一项 U_val^epi 为组内可约认知不足；第二项 U_val^ale 为组间稳定分歧（合法多元）。
需求侧：U_need^epi = H(n*|D) − H_min(D)，U_need^ale = H_min(D)，其中 H_min(D) 为在非扭曲约束与允许的 Q_val 下任何策略可达到的最小后验熵。U_need^ale 表示「再问也定不下来」的欠定或全新需求。注意价值侧的 aleatoric 不是噪声，而是**不可抹平的合法差异**。

**定义 315（请求≠需求与需求验证间隙）** 需求验证间隙
Δ_need(r) = max_{s∈N_sol} E_{n*~p(n*|r,D)}[σ(n*,y_s)] − E[σ(n*,y_{s_r})]。
若 Δ_need(r) > τ_need 且替代解 admissible，则直接执行 r 是需求劣势的。此时允许的响应是 q_offer_menu 或 q_prototype，**不是**静默替换（自主性约束）；除非 H 禁止 r。`q_prototype` 用于无法用语言表达时，用可选原型暴露偏好。

**定义 316（非扭曲 elicitation 与 revelation-robust VoI）** 设无问句反事实下的偏好为 θ^∅，执行 elicitation q 后的偏好为 θ^q。扭曲
D(q) = E_y[D_KL(p(θ^q|y) ‖ p(θ^∅|y))]（或偏好空间 Wasserstein）。
用 K 个语义等价框架 {φ_j} 的扰动估计 D̂(q)=max_{j,k} W_2(p(θ|φ_j(q)), p(θ|φ_k(q)))。定义
VoI_R(q) = VoI(q) − γD̂(q) − c(q)，
s.t. D̂(q) ≤ ε_manip，q ∉ 𝒱_vuln（不针对认知/情绪脆弱性），且框架不变性通过。仅当 VoI_R(q)>0 才允许问。
另定义谄媚风险 VoI_syc = 以「报告偏好」计的信息增益，VoI_true = 以留出的稳定偏好计的信息增益；要求 VoI_syc − VoI_true ≤ τ_syc。

**定义 317（增广元动作空间）** ξ=(a,g,q)，a∈𝒜_task，g∈𝒜_info（R69 的注视/探针/事实问句），q∈Q_val={q_ask_pref, q_offer_menu, q_prototype, q_defer, q_refuse}。策略 π_θ(ξ|o,v)。所有 q 必须通过 C-RAS-WM 认证与 R69 交互预算；q_defer/q_refuse 只能产生安全保持/决策简报，不得在同一前缀内继续执行任务动作。

**定义 318（来源与授权）** provenance 函数 prov 把执行目标的每个项映射到 2^S；授权谓词 Auth(i,term,ctx)∈{0,1}；consent ledger L 记录同意、范围、时间与撤回。合法目标项要求 ∃i: i∈prov(term) ∧ Auth(i,term,ctx)=1，且 term 不越出 A_i。硬约束 H 必须来自规范性授权（安全/法律/明确同意的监护），不能由偏好多数修改。未签名的项、冒充的利益相关者、范围蔓延（scope creep）一律非法。

**定义 319（聚合章程与可通约性）** 聚合章程 F: (P_leg,H)→2^𝒜 由治理方声明并写入证书；合法实例包括：字典序（H 优先，再按命名 owner）、maximin、Nash 谈判、单一 owner、菜单。Pareto 集 P={a | ∄a' s.t. ∀i u_i(a')≥u_i(a) 且 ∃i >}。**不可通约条件**：若 P 中动作让不同利益相关者互有胜负，且 U_val^ale>τ_plural，则 F 只能返回菜单或 defer；没有 F 的标量化非法。没有合法 F 时，系统不得自行发明权重。

**定义 320（价值漂移与滞后）** θ_i 在慢时间尺度 τ_θ（小时/天）上演化，m_i 在快时间尺度 τ_m（秒/分）上演化。θ_i 仅当变化点显著且持续 k 次观测/超过窗口 T 时更新；m_i 可即时更新但只影响当前 q 的选择。目标切换需超过滞后带 h。由此：一次情绪化表达不改变长期目标；真实漂移也不会被永久忽略。

**定义 321（代理可识别性与规格博弈）** 证据 D 诱导一致参数集 Θ(D)={θ: L(D|θ) ≥ L_max−δ}。可识别性间隙 G_id = sup_{θ,θ'∈Θ(D)} max_{y∈Y}|u(y;θ)−u(y;θ')|。若 G_id>τ_id，则代理目标不唯一，优化代理可能提高真实 regret；形式上存在 θ∈Θ(D) 使 argmax proxy ∉ argmax u(·;θ)，且 Regret ≤ G_id + ε_approx。故自主目标选择前必须通过可识别性检查。

**定义 322（目标风险与执行风险二维包络）** 执行风险 R_exec(a) 由 R69 的 λ 包络约束；目标风险
R_obj(a) = E_{θ~P_leg}[ max_{a'} u(y_{a'};θ) − u(y_a;θ) ]。
安全当且仅当 R_exec(a) ≤ ε_exec 且 R_obj(a) ≤ ε_obj。二者正交。在 A99（尺度不变结果特征）下，对任意 λ∈(0,1]，y_{λa}=y_a，故 R_obj(λa)=R_obj(a)——**λ_floor 只作用于 R_exec，无法给 R_obj 上界**。因此目标不确定时，允许的动作只有：经证的目标动作、q_offer_menu、q_prototype、q_defer。

**定义 323（价值对齐门 VAG）** 若价值模型校准 ECE_val>τ_ece，或 G_id>τ_id，或 F 未授权，或 provenance 不完整，则 VAG 关闭自主目标选择：系统只能执行**已经授权且目标固定**的 R69 任务，否则输出菜单/延迟，绝不自行推断一个新目标。

**定义 324（延迟/菜单作为一等安全动作）** q_defer/q_menu 产生决策简报
B = (options, Y 特征, 权衡, provenance, 残余 U_val/U_need, 默认建议, 过期时间)。
简报必须时间有界、可读、排序中立；延迟不是失败，而是经认证的安全动作。q_refuse 用于 H 冲突或授权缺失，记录理由。

**定义 325（审计与威胁模型）** VQA-W 审计：provenance 完整性、问句中立性、谄媚、偏好投毒、冒充、scope creep、代理博弈、漂移滞后。威胁模型
ℰ_WORTH = ℰ_FLUID × ℰ_pref × ℰ_need × ℰ_obj，
其中 ℰ_pref={谄媚、引导性框架、锚定、偏好投毒、假共识}；ℰ_need={需求注入、假利益相关者、范围蔓延、木马请求}；ℰ_obj={目标替换、代理劫持、Goodhart}。

**定义 326（证书 J_WORTH）** J_WORTH = (J_FLUID, provenance_digest, value_posterior_digest, need_graph_digest, aggregation_rule_id, U_val^ale/epi before/after, U_need^ale/epi before/after, D̂, authority_signatures, menu/defer record, T_cert, worth_ver)。Valid ⇔ Valid(J_FLUID) ∧ provenance 完整 ∧ H 满足 ∧ D̂≤ε_manip ∧（自主执行 ⇒ 可识别性通过 ∧ F 合法）∧ 多元性保持。

```python
# IP-264 VPM：利益相关者价值模型（慢回路，结果缓存进证书）
class ValuePreferenceModel:
    def posterior(self, S, D):                 # 耐久 θ 与瞬时 m 分开
        return {i: (q_theta(i, D), q_state(i, D)) for i in S}

    def durable_update(self, i, D):            # 仅持续证据才改 θ（定义 320）
        if change_point_significant(D) and persistent(D, k=3, T=WINDOW):
            return q_theta(i, D)
        return self.theta_hat[i]               # 否则只改 m

# IP-265 NHG：请求 -> 需求反演，并检查替代解
def need_abduction(request, G_need, D):
    post = bayes_invert(request, G_need, D)    # p(n* | r, D)
    alt  = best_alternative(G_need, post)      # 最大化 E[σ(n*, y_s)]
    gap  = expected_satisfaction(alt, post) - expected_satisfaction(request, post)
    return post, alt, gap

# IP-266 VUD：价值/需求不确定性四通道
def decompose(vpm, need_post, D):
    U_val_epi = mean_i(var(theta_i | D))       # 组内：可问
    U_val_ale = var_i(mean(theta_i | D))       # 组间：合法多元，不可问
    H_now     = entropy(need_post)
    H_min     = min_admissible_entropy(need_post, Q_val, EPS_MANIP)
    U_need_epi, U_need_ale = H_now - H_min, H_min
    return U_val_epi, U_val_ale, U_need_epi, U_need_ale

# IP-267 NEL：非扭曲 elicitation，标准 VoI 不合法时拒绝提问
def choose_elicitation(vpm, need_post, o, budget):
    best = None
    for q in Q_val:
        if not budget.allow(q) or not c_ras_wm.certify_info(q, o): continue
        d_hat = framing_distortion(q, K_FRAMINGS)          # 定义 316
        if d_hat > EPS_MANIP or q in VULNERABLE_TARGETS:   continue
        voi = standard_voi(q) - GAMMA * d_hat - cost(q)
        if best is None or voi > best.voi: best = (q, voi, d_hat)
    return best if best and best.voi > 0 else None

# IP-268 PAX：给目标逐项验来源与授权；任何匿名项直接作废
def authorize(objective, S, consent_ledger):
    for term in objective.terms:
        if not any(i in prov(term) and Auth(i, term, ctx) for i in S):
            return INVALID(term, 'no_provenance_or_authority')
        if term in objective.tradable and term in H:
            return INVALID(term, 'hard_constraint_traded')
    return SIGNED(objective, signatures=collect_signatures(objective))

# IP-269 ACT：合法聚合；不可通约时只返回菜单
def aggregate(value_post, H, F):
    if F is None or not F.authenticated:
        return MENU(value_post)
    P = pareto_set(value_post, H)
    if crossing_preferences(P) and U_val_ale(value_post) > TAU_PLURAL:
        return MENU(P)                               # 禁止私自标量化
    return F.select(P)                               # F 必须已授权

# IP-276 WORTH-RAS 主闭环：价值层只在慢回路决策，控制回路仍守 2.6ms
def WORTH_RAS_round(M, obs, request):
    z, o = M.mtm.forward(...)                        # R69 一次前向
    vpost = M.vpm.cached_posterior()                 # 证书有效期内的缓存
    need_post, alt, gap = M.nhg.abduct(request, M.need_graph, M.history)
    Uve, Uva, Une, Una = M.vud.decompose(vpost, need_post, M.history)

    # 1) 可约：非扭曲 elicitation / 需求验证；否则继续
    if Uve + Une > TAU:
        q = M.nel.choose_elicitation(vpost, need_post, o, M.budget)
        if q is not None:
            return M.nel.execute(q)                  # 含 offer_menu / prototype
    # 2) 不可约：菜单或延迟，绝不标量化
    if Uva > TAU_PLURAL or Una > TAU_NEED:
        return M.dba.menu_or_defer(vpost, need_post, reason='irreducible')
    # 3) 需求验证：直接执行是需求劣势时，给选项而不是静默替换
    if gap > TAU_NEED and alt is not None:
        return M.dba.menu_or_defer(vpost, need_post, reason='need_gap', options=[request, alt])
    # 4) 聚合 + 授权 + 可识别性门
    obj = M.act.aggregate(vpost, M.H, M.F)
    if not M.vag.pass_gate(vpost, obj):              # ECE / G_id / F / provenance
        return M.dba.menu_or_defer(vpost, need_post, reason='gate')
    cert = M.pax.authorize(obj, M.S, M.consent)
    if not cert.valid:
        return M.dba.defer(vpost, need_post, reason=cert.reason)
    # 5) 已授权目标交给 R69 执行层；控制回路不变
    k, lam, mode, U = M.fluid_round(obs, objective=obj)
    # 6) 目标风险独立复核；超界则否决执行（λ 不能替代这一步）
    if M.ora.objective_risk(obj, vpost) > EPS_OBJ:
        return M.dba.defer(vpost, need_post, reason='objective_risk')
    M.vqa_w.submit_async(obj, cert, Uve, Uva, Une, Una, U)
    return k, lam, mode, (U, Uva, Una)
```

## 3. 推导

**引理 19（目标风险不可收缩）** 在 A99（结果特征尺度不变：对任意 λ∈(0,1]，y_{λa}=y_a，只有时间/幅值变化）下，R_obj(λa)=R_obj(a)。R69 的 λ_floor 只约束 R_exec，且 R_exec 随 λ↓单调不增；因此对任意给定的 ε_obj<R_obj(a)，总存在 λ 使 R_exec≤ε_exec 但 R_obj>ε_obj。即：**R69 能执行一个「很慢、很稳、但目标错误」的动作而完全通过其安全证书**。证明：R_obj 只依赖所选结果特征，不依赖正缩放；R_exec 依赖幅值。取 λ*=min{λ: R_exec(λa)≤ε_exec} 即可。证毕。
（若 A99 不成立，λ 可能偶然降低 R_obj，但无可证上界；因此不能作为机制。）

**引理 20（合法多元的下界）** 设两个利益相关者 i,j 的耐久价值为点质量，存在动作 a,b 使 u_i(a)>u_i(b)、u_j(b)>u_j(a)，且差距均 ≥Δ。任何单一动作都会让至少一方 regret ≥Δ；增加证据不会改变点质量，故再问无益。没有合法 F 时，唯一不擅自偏袒的输出是菜单（或延迟）。若菜单可同时提供 a,b，选择者的 ex-post regret 为 0；若必须单点执行，则任何确定性策略的期望 regret ≥min(ℓ_i,ℓ_j)·Δ。证毕。

**引理 21（非扭曲 elicitation 的上界）** 设报告偏好满足 θ^q = θ^∅ + B(q) + ξ，框架敏感度 ‖B(q)‖≤β·diam(Φ)，效用对 θ Lipschitz。则 D(q)≤β·diam(Φ)+σ_ξ。存在引导性问题 q_lead 使标准 VoI(q_lead) 高但 D(q_lead)>ε_manip（用「你是不是也认为……」制造同意），故标准 VoI 不是对齐安全的。采用 VoI_R=VoI−γD̂ 并加硬约束 D̂≤ε_manip 后，任何被选中的 q 满足 D(q)≤ε_manip+估计误差。证毕。

**引理 22（需求验证优于直接执行的条件）** 若 Δ_need(r)>c_menu（菜单/原型的成本），且替代解 admissible，则在自主性约束下，提供菜单的期望需求满足度 ≥直接执行 r；若 Δ_need(r)≤c_menu，则直接执行 r 不劣。证明：菜单让授权者选 s*，由 Δ_need 定义其期望 σ 至少高 Δ_need；减去成本 c_menu 仍为正。自主性约束禁止系统静默替换，故「给选项」是唯一既提升需求满足又不越权的动作。证毕。

**定理 18（WORTH 严格包含 R69）** 在退化条件下：|S|=1、p(θ) 为点质量（U_val=0）、r=n*（U_need=0）、D=0（无扭曲威胁）、F 为单一 owner、Q_val 不启用，则 VAG 必通过，PAX 必签名，ORA 的 R_obj=0，NEL 不被调用，WORTH 主闭环逐指令退化为 R69 的 FLUID_RAS_round。反向，在非退化价值不确定性下，由引理 19，R69 的 λ 无法给 R_obj 上界；WORTH 要么给出经证目标、要么菜单/延迟，因此 WORTH 的安全作用域严格更大，且不削弱 R69 的执行安全。证毕。

**定理 19（来源—延迟安全性）** 在 ℰ_WORTH 下，任何被 WORTH 执行的任务动作都满足：(a) 通过 J_FLUID 执行证书；(b) 目标项通过 PAX 来源/授权检查；(c) 通过 ORA 的目标风险复核；否则动作只能是 q_offer_menu/q_prototype/q_defer/q_refuse。伪造项因签名失败被拒；冒充者不进入 S；谄媚型 elicitation 被 VoI_R 的 D̂ 约束拦截；单次情绪化表达因 θ 的滞后更新不改变耐久目标；代理博弈因 G_id 门被拦截。故不存在「未授权目标被执行」的路径，且值侧操纵的位移 ≤ε_manip+估计误差。证毕。

**推论 18.1（菜单不是退步）** 在不可通约且无合法 F 时，菜单的期望 regret 低于任何未授权标量化（引理 20），且不降低执行安全（定理 19）。因此「把决定交还」是对齐框架内的一等安全动作，而不是能力不足的兜底。

## 6. 次级风险与缓解

1. **价值模型谄媚**：模型把「用户当场同意」当学习信号 → 用 VoI_R 的 D̂ 约束 + 留出稳定偏好 + E303/E306；
2. **来源伪造与冒充**：伪造利益相关者签名 → PAX 签名/范围/同意账本 + 人工复核高风险目标；
3. **延迟滥用**：系统用 defer 逃避决策 → 延迟成本计入 utility + E307 的人类负担指标；
4. **菜单疲劳**：选项过多导致用户随机选 → ε-cover 小菜单（≤3）+ 默认建议（排序中立）；
5. **多元性瘫痪**：所有决策都变成菜单 → 有合法 F 且可识别时必须自主执行，菜单只用于不可通约/授权缺失；
6. **偏好隐私**：价值后验含敏感信息 → 本地化、最小化、可撤回；
7. **慢回路延迟**：价值推理拖慢任务 → 证书缓存 + 过期即安全保持，不在控制回路跑大模型；
8. **跨文化误读**：把群体刻板印象当先验 → 个体证据优先、群体先验仅作弱正则 + E313。

## 7. 本轮最大风险

**一句话**：WORTH-RAS 的全部安全性押在「来源/授权层不可伪造、价值后验不被谄媚污染」上——**一旦攻击者能冒充合法利益相关者，或价值模型把用户的当场顺从误学成耐久价值，系统就会用一张看似完备的证书，把一个被制造出来的目标认证为「对齐的」，从而把 R69 的「问错问题」升级为「给错误目标盖上合法印章」**——被授权的错，比不被授权的错更难纠正。

**定义 311（价值对齐）** `u_exec` 对齐 ⇔ (a) 每项有 provenance 且授权；(b) `u_exec ∈ F(P_leg,H)`；(c) H 从不交易；(d) 形成 `P_leg` 的 elicitation 满足非扭曲。用户当场「满意」不是对齐的定义，只是可能被问句制造的行为代理。

**定义 316（非扭曲 elicitation）** `VoI_R(q)=VoI(q)−γD̂(q)−c(q)`，s.t. `D̂≤ε_manip`、`q∉𝒱_vuln`、框架不变；另约束 `VoI_syc−VoI_true≤τ_syc`（谄媚风险）。

**定义 321（可识别性与代理博弈）** `Θ(D)={θ:L(D|θ)≥L_max−δ}`，`G_id=sup max_y|Δu|`；`G_id>τ_id` ⇒ 代理不唯一，优化代理可增 regret（`Regret≤G_id+ε_approx`），禁止自主目标选择。

**定义 322（二维风险包络）** `R_obj(a)=E_θ[max_{a'}u(y_{a'};θ)−u(y_a;θ)]`；安全 ⇔ `R_exec≤ε_exec ∧ R_obj≤ε_obj`。A99（尺度不变结果特征）下 `R_obj(λa)=R_obj(a)`，故 λ_floor 只约束 R_exec，对 R_obj 无界。

**定义 323–324（VAG / 延迟）** ECE_val、G_id、F 授权、provenance 任一越界 ⇒ 禁自主目标选择，只能做已授权固定目标或菜单/延迟；`q_defer/q_menu` 输出决策简报 B（选项/权衡/来源/残余不确定性/默认建议/过期），是一等安全动作。

**定义 325–326（威胁模型 / 证书）** `ℰ_WORTH=ℰ_FLUID×ℰ_pref×ℰ_need×ℰ_obj`；`J_WORTH=(J_FLUID, provenance_digest, value_posterior_digest, need_graph_digest, F_id, U_val/U_need before-after, D̂, signatures, menu/defer record, T_cert, worth_ver)`。

```python
def need_abduction(request, G_need, D):

    alt  = best_alternative(G_need, post)
    gap  = expected_satisfaction(alt, post) - expected_satisfaction(request, post)

    U_val_ale = var_i(mean(theta_i | D))

    return SIGNED(objective, signatures=collect_signatures(objective))

def aggregate(value_post, H, F):

    P = pareto_set(value_post, H)

def WORTH_RAS_round(M, obs, request):
    z, o = M.mtm.forward(...)
    vpost = M.vpm.cached_posterior()
    need_post, alt, gap = M.nhg.abduct(request, M.need_graph, M.history)
    Uve, Uva, Une, Una = M.vud.decompose(vpost, need_post, M.history)
```

## 4. 推导

**引理 19（目标风险不可收缩）** A99（尺度不变结果特征）下 `R_obj(λa)=R_obj(a)`，而 `R_exec(λa)` 随 λ↓单调不增。故存在 λ 使 R_exec≤ε_exec 但 R_obj>ε_obj：R69 可执行一个「很慢、很稳、但目标错误」的动作而通过其全部证书。λ_floor 不能给目标风险上界。

**引理 20（合法多元的下界）** 两利益相关者点质量价值、交叉偏好、差距 ≥Δ：任何单一动作至少让一方 regret ≥Δ；更多数据不改变点质量，再问无益；无合法 F 时唯一中立输出是菜单。若菜单可含两动作，选择者 ex-post regret 为 0；若强制单点，期望 regret ≥min(ℓ_i,ℓ_j)·Δ。

**引理 21（非扭曲上界）** 报告偏好 `θ^q=θ^∅+B(q)+ξ`，`‖B(q)‖≤β·diam(Φ)`，则 `D(q)≤β·diam(Φ)+σ_ξ`。存在高标准 VoI 但高扭曲的引导性问题（制造同意），故标准 VoI 不对齐安全；`VoI_R=VoI−γD̂` 且 `D̂≤ε_manip` 后，被选 q 的扭曲 ≤ε_manip+估计误差。

**引理 22（需求验证条件）** 若 `Δ_need(r)>c_menu` 且替代解 admissible，则在自主性约束下，提供菜单的期望需求满足度 ≥直接执行 r；若 `Δ_need≤c_menu`，直接执行不劣。菜单是唯一既提升需求满足又不越权的动作。

**定理 18（WORTH 严格包含 R69）** 退化条件（|S|=1、θ 点质量、r=n*、D=0、F 单一 owner、不启用 Q_val）下，VAG 通过、PAX 必签、R_obj=0、NEL 不调用，主闭环逐指令退化为 R69 的 FLUID_RAS_round。非退化时由引理 19，R69 无法给 R_obj 上界；WORTH 要么给经证目标、要么菜单/延迟，故安全作用域严格更大且不削弱执行安全。

**定理 19（来源—延迟安全性）** ℰ_WORTH 下，任何被执行的任动作都满足：过 J_FLUID、过 PAX 来源/授权、过 ORA 目标风险；否则只能是 menu/prototype/defer/refuse。伪造项签名失败、冒充者不进 S、谄媚被 D̂ 拦截、单次情绪不改 θ、代理博弈被 G_id 拦截。故无「未授权目标被执行」路径，值侧操纵位移 ≤ε_manip+估计误差。

**推论 18.1（菜单不是退步）** 不可通约且无合法 F 时，菜单 regret 低于任何未授权标量化（引理 20），且不降低执行安全（定理 19）。

## 7. 本轮最大风险

**一句话**：WORTH-RAS 的安全性押在「来源/授权层不可伪造、价值后验不被谄媚污染」上——**一旦攻击者能冒充合法利益相关者，或价值模型把用户的当场顺从误学成耐久价值，系统就会用一张看似完备的证书，把一个被制造出来的目标认证为「对齐的」，把 R69 的「问错问题」升级为「给错误目标盖上合法印章」**；被授权的错，比不被授权的错更难纠正。
