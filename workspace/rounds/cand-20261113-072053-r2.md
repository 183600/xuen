# 第 3 轮迭代（灵感循环 v3：「力觉传感」×「语义分割」）—— 在没有力传感器的接口上，重建“接触状态”

> **直觉先行。** v2 把“进度验证”做成了视觉/几何判据：看子目标有没有完成。但真正丢分的步骤几乎都在**接触密集**处——插网线、合盖、拧盖、拉拉链、叠毛巾、装耳机。这些步骤的成败不取决于“看起来像不像”，而取决于“有没有真正接触、有没有滑、有没有卡住、有没有被顶回去”。而这套接口**没有力/触觉，也没有深度、没有基座位姿、没有力矩/电流**（见 §0）。所以本轮的核心问题不是“加一个力传感器”，而是：**力觉信息能不能被“制造”出来？**
>
> 我的答案是把两件事拼起来：**语义分割**负责“这是哪个物体/哪个部件、处在什么关系”，回答 **what/where**；**力觉代理**负责“刚刚那一下是不是接触、滑了没有、卡了没有”，回答 **when/how hard**。前者慢、全局、抗部分遮挡；后者快、局部、对接触敏感。两者的失效模式几乎正交，天然适合做**因子化状态机**。旗舰因此从 v2 的 RHPV-D 升级为 **FSCM（Force-Semantic Contact-state Machine，力-语义接触状态机）**，并配一个关键机制：**把探针写进固定长度的动作块里**——用“主动本体感受”把不可见的接触变成下一次观测可见的状态变化。

**两条硬修正直接改变方案形态：**

1. **反应性不能靠“运行时改块长”。** `T_a` 是常量，只能**离线按任务族选**（接触密集任务选小 `T_a`），或者在**块内动作设计**上做文章（见 UIP-19 的探针）。
2. **“每一步都能验证”是错觉。** 两次观测之间隔着整块开环执行；力/触觉不可得。因此“力觉”必须被定义为**可观测代理**，而不是物理力矩；并且要明确哪些量**根本不可辨识**。

### 0.1 可观测性审计（本轮方法论的核心）

| 想知道的量 | 接口内可辨识吗 | 可用的代理信号 | 结论 |
|---|---|---|---|
| 绝对接触力（N·m） | **不可** | 无 torque/current，低层控制器还会补偿掉一部分残差 | 不要回归绝对力；最多回归相对负载分位 |
| 是否接触 | 部分可 | EE/关节“指令-实际”残差、夹爪堵转、腕部相机中物体与夹爪的遮挡/形变 | 可做事件级接触检测 |
| 是否夹住 | 可 | 夹爪目标开度 vs 实际开度；腕部物体 mask 相对夹爪的运动 | 可靠度较高 |
| 是否打滑 | 部分可 | 夹爪开度漂移 + 物体 mask 相对夹爪的光流 | 可做滑移事件 |
| 插入是否到位 | 部分可 | 轴向“推进-保持-回抽”探针的残差 + 分割遮挡/重叠 | 可做 seated/jam 分类 |
| 是否被人反向撤回 | 可（在块边界） | 语义关系反转 + 接触/负载事件 + 反事实动作归因 | 可做，但需归因防误判 |

> **命题（非可辨识性，直觉版）**：若两个不同的接触力分布能在低层控制器作用下产生完全相同的关节位置、EE 位姿、夹爪开度和图像序列，则仅凭接口观测无法区分它们。因此 FSCM 只承诺识别**接触模式与事件**，不承诺估计力的大小；任何“用视觉回归牛顿”的说法都应被视为不可检验的过度承诺。

## 1. 上轮清单诊断（v2 → v3 该升、该退、该改）

- **升级为旗舰**：UIP-01′（滚动验证）与 UIP-09′（撤回检测）合并为 **FSCM**。v2 的验证器是“视觉阈值分类器”，v3 改成“**因子化接触-语义状态 + 反事实进度归因**”。
- **退役**：UIP-13 ACS（自适应块长）。硬形状校验使其在接口层不成立；其合理内核“按阶段控反应性”转移到 **UIP-19 主动探针**与“离线选 `T_a`”。
- **职责升级**：UIP-11 GSO 与 UIP-12 DRF 从“计分神谕/造数据”升级为 **接触与分割的标签工厂**——Gazebo 物理引擎能直接给出接触力、接触点、滑移和**完美实例 mask**，这恰好补上公开数据“无力标签、无部件 mask”的空白。
- **保留**：UIP-02′（计分步安全网）、UIP-05（语言→可供性）、UIP-08′（多端口延迟工程）、UIP-14（技能图）——其中 UIP-14 的技能图在 v3 里多了一个身份：**进度归因的转移动模型**（哪些“回退”是任务本身允许的，哪些只能是外部干扰）。
- **改写**：UIP-15 CSG 增加“探针预算/重做预算”，防止“为了测接触而无限试探”。

## 2. 两个灵感词的解读（先直觉，再定义）

### 2.1 力觉传感：把“力”改写成“接触模式”

**直觉**：人拧瓶盖时并不读牛顿值，而是读“开始吃力—持续吃力—突然一松（到位）—打滑（空转）”。机器人需要的也是这套**离散接触事件**，而不是一个精密测力计。

**严谨定义**：设 `c_t ∈ C = {free, contact, grasp, slip, jam, seated}` 为接触模式。我们估计的是后验 `p(c_t | o_{0:t}, A_{<t})`，其中 `o_t = (I_t^{1..4}, q_t, e_t, g_t, b_t, l)`，`A_{<t}` 是已下发的动作块（efference copy，用作“我本来想做什么”的参照）。证据有三路：

1. **本体感受残差**：`r_t = a^{cmd}_{t-1} - q_t`（joint 空间）或 `e^{cmd}_{t-1} - e_t`（ee 空间）。自由空间里残差小且各向同性；接触/卡住时残差沿任务轴集中；但低层控制器会吸收一部分，因此只能用**归一化后的方向性与时序形状**，不能用绝对幅值。
2. **夹爪堵转**：`g_t` 对 `g^{cmd}` 的跟随误差。闭合时“停在半路”= 夹住；“一路合到底”= 抓空；保持期开度缓慢增大 = 滑移。
3. **腕部视觉触觉**：腕部相机离接触最近。用部件分割得到物体与夹爪指面的 mask，计算两者的**相对光流、遮挡率、接触带宽度、软物体形变**。这不是触觉阵列，但在夹持/滑移/插入遮挡上是可用的“视觉触觉”。

**训练标签从哪来**：Gazebo 的接触求解器直接给 `contact flag / normal force / contact point / slip`；UIP-11/12 的仿真 rollout 就是免费标注机。真机没有标签，只做**事件级弱监督 + 域适应**（夹爪堵转、残差、mask 光流本身可作为弱标签）。输出**带不确定度的模式分布**，不确定度高时状态机不动作。

### 2.2 语义分割：把像素改写成“部件关系账本”

**直觉**：32 个任务里真正决定分数的往往不是整只杯子，而是**拉链头、网口、瓶盖螺纹、碗沿、毛巾角、耳机盒盖**。整图分类会把这些细节平均掉；部件级分割不会。

**严谨定义**：为每帧四视图输出一组**类无关实例 mask** `{m_t^k}` 与**部件标签** `{p_t^k}`（由语言提示绑定，如 “zipper slider”“RJ45 plug”“bowl rim”“towel corner”）。由此构造**关系图** `r_t`，节点是部件，边是关系谓词 `on/in/closed/stacked/inserted/covered/held_by`。每个计分步对应一个谓词 `π_s(r_t) ∈ {true,false,unknown}`。进度分 `Φ_t = Σ_s w_s · 1[π_s(r_t)=true]`。

**为什么要分割而不只用 VLM 问答**：
- 分割给出**像素级定位与遮挡关系**，能判断“插头是否真的进入网口”这类几何事实；VLM 容易只凭语义先验“猜完成”。
- 类无关 + 部件提示可以迁移到**未见物体/未见背景**；VLM 的开放词汇能力可留在离线打标阶段。
- 分割 mask 是**时序可比**的：`Δm` 比原始像素更抗光照/背景变化，适合做“进度差分”。

**合规要点**：离线用 SAM2/GroundingDINO/Florence 生成伪标签是训练手段，**不算提交模型**；推理期**只允许**共享主干上的轻量分割头/蒸馏头，绝不调用外部大模型，避免“多模型”合规争议。

### 2.3 融合：两个正交的失效模式

- 力觉代理在**透明、反光、软物体**上容易失真；分割在**遮挡、细接触、快速运动模糊**上容易丢。
- 力觉代理是**事件级**（接触/滑/卡），分割是**关系级**（谁在谁上面/里面）。
- 因此用**因子化状态** `z_t = (c_t, r_t)`：接触模式解释“刚才发生了什么物理事件”，关系图解释“现在世界处于什么配置”。`c_t` 的突变可用于**门控** `r_t` 的更新（例如“听到/感到一下松脱”才允许把“拧紧”改成“已打开”），降低误判。

## 3. 瓶颈假设（更新）

- **H1（最高杠杆）**：接触密集步骤的丢分，主因不是“不会做”，而是**不知道自己正在接触/滑/卡/被顶回**；接口不提供力，谁先造出可靠的接触事件信号，谁就先拿到这部分分数。
- **H2**：绝对力不可辨识，**回归牛顿值是陷阱**；只做事件/相对量级，才能跨真机与仿真迁移。
- **H3**：部件级语义差分 + **反事实归因**可以区分“我自己把盖子拧回去（任务允许的回退）”与“人把盖子拧回去（外部撤回）”，从而避免 v2 的“done→undone 就重做”造成的大量假重做。
- **H4**：在固定 `T_a` 的块内嵌入**探针**（按压-保持、夹紧-保持、轻拉-回抽），能把接触变成下一次观测可测的状态差；代价是少量时间与被扰动的风险。
- **H5**：多视分割蒸馏 + 仿真完美 mask，足以支撑部件关系判别；推理期不需要外部分割大模型。

## 4. 形式化：FSCM 的一句话定义

> **FSCM = 一个以“接触模式 × 部件关系图”为隐状态的因子化切换系统；用 VFS（力觉代理）与 PAS（部件分割）作观测；用“进度势 Φ + 反事实动作归因”判定外部撤回；只重做被回退子目标的最小依赖后缀。**

其中“外部撤回”的判据不是简单的 `Φ` 下降，而是：

```text
regressed(s) ⇔ π_s 由 true 变 false
              ∧ 该回退不能用“我刚执行的动作所属技能图的合法反向边”解释
              ∧ 接触/负载事件与语义反转在时间上对齐（块边界附近）
```

`Φ` 的计分权重直接取 §2 的 100 分表：前置步权重不一定小（2 步任务是 50/50），所以“只保末步”是错的；应按**依赖闭包**决定重做的优先级。

## 5. 候选与合并 → v3 清单（详见产物区）

围绕两词发散 8 个草案，合并后得到 v3：旗舰 **UIP-18 FSCM**，两条腿是 **UIP-16 VFS**（虚拟力觉）与 **UIP-17 PAS**（部件级分割），两个执行机制是 **UIP-19 APP**（主动探针）与 **UIP-20 PLA**（进度账本与反事实归因）；退役 UIP-13，升级 UIP-11/12 为标签工厂，其余 v2 资产保留。

## 6. 本轮最大风险

**一句话**：最大的风险是把“不可观测的力”当成可观测的量——如果 FSCM 把仿真学来的接触事件当成真机真值，错误的 `regressed` 会触发反复重做，反而同时伤害成功率、步骤分与延迟可信度；因此必须把 VFS 限定为**事件级、带拒识的软证据**，并以真机小样本校准与 UIP-15 的预算护栏兜底。

## 1. 旗舰深潜：UIP-18 · FSCM（Force-Semantic Contact-state Machine）

### 1.1 状态与证据

```text
隐状态 z_t = (c_t, r_t)
  c_t ∈ {free, contact, grasp, slip, jam, seated}      # 接触模式（VFS 输出分布）
  r_t = 部件关系图（节点=部件 mask/标签，边=on/in/closed/stacked/inserted/held_by）
观测证据：
  E_vfs = p(c_t | I_{1:4}, q_t, e_t, g_t, A_{t-1})       # 力觉代理（UIP-16）
  E_pas = {m_t^k, p_t^k, track_id}                       # 部件分割（UIP-17）
转移模型：
  P(c_t | c_{t-1}, skill_t, a_{t-1})                     # 技能图 + 动作意图（UIP-14）
  P(r_t | r_{t-1}, c_t, skill_t)                         # 接触事件门控关系更新
```

### 1.2 与 v2 的本质差异

| 维度 | v2 RHPV-D | v3 FSCM |
|---|---|---|
| 验证器 | 视觉/几何阈值分类器 | 接触模式 × 部件关系图，两路软证据融合 |
| 撤回判定 | `done → undone` 即 `regressed` | 还要求“无法由自身动作的合法反向边解释”，并做时间对齐 |
| 重做范围 | 重做当前子目标 | **最小依赖后缀**，按计分权重与依赖闭包排序 |
| 反应性 | 想运行期改 `k`（不成立） | 离线选 `T_a` + 块内探针（UIP-19） |
| 接触密集步 | 只能“看” | 有事件级接触/滑/卡证据 |
| 力 | 未建模 | 明确“事件级、不可辨识绝对值”的 VFS |

### 1.3 反事实进度归因（本旗舰最关键的一步）

设技能图 `G=(S,E)`，其中边分两类：`E+`（前进）与 `E-`（任务本身允许的回退，如“先打开再合上”）。执行动作块 `A` 后观察到 `r_t`：

```text
ΔΦ = Φ(r_t) - Φ(r_{t-1})
expected = E_{skill}[ΔΦ]                     # 由技能图/仿真转移模型给出的期望进度变化
if ΔΦ < 0:
    if (skill, reverse_edge) ∈ E- and π_s 的翻转方向与 E- 一致:
        cause = "intentional_undo"           # 自己按任务需要回退，不惩罚
    elif VFS 在块边界附近检测到外部接触/负载事件:
        cause = "external_regression"        # 人为撤回，进入重做
    else:
        cause = "action_failure"             # 动作没做成，重试而非重做
```

> 这一步直接修掉 v2 的一个隐患：很多任务本身就有“开→合”“拧开→拧紧”“拉上→拉开”的合法序列；若把所有 `done→undone` 都当外部撤回，会大量假重做。**归因**把“状态回退”拆成三类，重做策略才可信。

### 1.4 重做调度：最小依赖后缀

```text
regressed_steps = {s : cause_s = external_regression}
S* = dependency_closure(regressed_steps, G)            # 只包含被回退步及其后继依赖
priority(s) = w_s · P(redo_success | c_t, r_t) / cost_time(s)
```

若无法确认计分是“曾经达成即入账”还是“终局状态结算”，采用**稳健策略**：对“是后续步前置条件”的回退立即重做；对“无后继依赖”的回退，若时间预算充足则重做，否则保留并优先确保后续步。这样在两种计分语义下都不至于崩。

### 1.5 风险

- VFS 误报 `external_regression` → 触发重做循环。护栏：置信度门限、连续两次证据一致才确认、最大重做次数、延迟预算（UIP-15）。
- PAS 在透明/反光/软物体上丢失部件 → 关系谓词返回 `unknown`，此时 FSCM 只前进不重做，等待下一次观测。

## 2. UIP-16 · VFS（Virtual Force Sensing，虚拟力觉）

### 2.1 三路证据与特征

| 证据 | 原始信号 | 特征 | 能识别 |
|---|---|---|---|
| 本体感受残差 | `a^{cmd}_{t-1}` 与 `q_t`/`e_t` | 沿任务轴的分量、各向异性比、残差的时序形状（上升/平台/突降） | contact, jam, seated |
| 夹爪堵转 | `g_t` vs `g^{cmd}` | 闭合停止位置、保持期开度漂移率、闭合速度 | grasp, slip, 抓空 |
| 腕部视觉触觉 | 腕部 RGB + PAS mask | 物体 mask 相对夹爪指面的光流、遮挡率、接触带宽度、软物体形变 | grasp, slip, contact |

### 2.2 训练：仿真给标签，真机给弱标签

```text
仿真（UIP-11/12）标签：contact flag、contact point、normal force、slip
  —— Gazebo 接触求解器直接给出；同时导出完美实例/部件 mask。

监督目标（真机不承诺绝对力）：
  L = BCE(contact_hat, contact*) + BCE(slip_hat, slip*)
      + CE(mode_hat, mode*) + λ·SmoothL1(load_hat, quantile(force*))
      + μ·domain_align(feature_sim, feature_real)

真机弱标签（无人工标注）：
  夹爪闭合停在半路 → grasp=1
  保持期开度缓慢增大 → slip=1
  残差沿任务轴持续偏高且位置不前进 → jam=1
  残差突降 + 部件关系翻转 → seated/regressed 候选
```

### 2.3 输出与拒识

VFS 输出的是**校准后的模式概率 + 不确定度**，不是力值。定义拒识：若最大类概率 `< τ_c` 或熵 `> H_max`，返回 `unknown`，FSCM 不据此做重做决策。这样把“不可辨识”变成“显式未知”，而不是自信的错误。

### 2.4 仿真到真机的边界

- 只迁移**事件级**判别（有/无接触、夹住/滑、卡住/到位），不迁移力的绝对值。
- 用 Gazebo 物理参数随机化（摩擦、质量、阻尼、接触刚度）做域随机化；真机用少量“按压-保持”“夹紧-保持”交互校准阈值。
- 把 VFS 当作**软证据**，与 PAS 做与/或门控；任一通道不确定则不重做。

## 3. UIP-17 · PAS（Part-Aware Segmentation，部件级语义分割）

### 3.1 结构（单模型合规）

```text
共享 VLA 视觉主干
   ├── 动作头（原有）
   ├── 类无关实例 mask 头（轻量，1–3M 参数）
   └── 部件标签头（由 language 提示调制，输出 K 个部件槽）
```

- **推理期只跑这一个 checkpoint**；分割头与动作头共享主干，满足“单模型多任务”。
- **离线**才用 SAM2 / GroundingDINO / Florence 生成伪标签与跟踪；这些外部模型不进入提交物。

### 3.2 标签工厂流水线

```text
1) 对 32 个数据集的 4 路视频，用 SAM2 做类无关实例分割 + 视频跟踪，得到稳定 track_id。
2) 用 GroundingDINO/Florence + 任务语言（"zipper", "RJ45 plug", "bowl", "towel"）给 track 打物体/部件标签。
3) 用 Gazebo（UIP-11）对代表任务渲染**完美实例/部件 mask**，补充透明/反光/遮挡难例。
4) 时序一致性过滤：track 断裂、mask 面积跳变、标签冲突的片段丢弃或降权。
5) 蒸馏到共享主干上的轻量头；在保留的未见物体/背景视频上评估 mask IoU 与关系谓词准确率。
```

### 3.3 关系谓词与进度

| 谓词 | 判定（多视图） | 对应任务例 |
|---|---|---|
| `closed(zipper)` | 拉链头 mask 位于齿列顶端 + 两片布 mask 相接 | T19 ZipUp |
| `inserted(plug, port)` | 插头 mask 与网口 mask 重叠/遮挡 + 轴向接触事件 | T26 PlugInEthernet |
| `stacked(bowl_i, bowl_j)` | 两碗 mask 的中心投影重合 + 上方碗底可见性 | T27 StackBowls |
| `folded(towel, k)` | 毛巾 mask 的宽高比/折线数量达到第 k 折 | T16 FoldTowel |
| `seated(cap, bottle)` | 瓶盖 mask 相对瓶口下移到位 + VFS 的“突松/到位”事件 | T14 PourOutMedicine |
| `held(obj, gripper)` | 物体 mask 与夹爪指面相邻 + 夹爪堵转 | 所有抓取步 |

`s` 计分步的谓词为真、且连续 `n` 帧稳定（滞回）才记 `true`；由 `true→false` 且非自身合法回退，才进入撤回候选。

### 3.4 泛化

- **类无关**：先分割“物体性”，再用语言绑定名字/部件，避免只认训练集类别。
- **部件级**：把“未见物体”拆成“可见部件”的组合（把手、盖、口、齿、绳），比整物体分类更容易迁移。
- **背景/位置**：分割 mask 的关系谓词对背景不敏感；配合 UIP-05 的语言→可供性，处理位置/干扰物变化。
- **失败模式**：透明/镜面/细长物体、强遮挡、运动模糊。用仿真难例 + 多视图一致性 + 不确定度拒识。

## 4. UIP-19 · APP（Active Proprioceptive Probing，主动本体感受探针）

### 4.1 机制

`T_a` 形状固定，但**块内动作内容**可控。把最后 `p` 步设计成“探针”：

| 场景 | 探针动作（块尾 p 步） | 下一次观测能读到什么 |
|---|---|---|
| 抓取 | 闭合到目标开度后**保持** | 夹爪是否停在半路（夹住）、是否一路合到底（抓空） |
| 插入 | 沿插入轴**小步推进-保持-轻微回抽** | EE 残差是否沿轴堆积、是否突然释放（到位） |
| 拉链/折叠 | 轻拉-保持 | 物体 mask 是否跟随、是否滑脱 |
| 拧盖 | 小角度拧-保持 | 残差是否持续、是否突松 |

关键点：探针**不改变动作块形状**，只是改写块尾动作；评测端整块执行后，下一次 `get_action` 的观测就包含探针引发的状态变化。这把“开环盲区”变成了“可控实验”。

### 4.2 预算与安全

- `p ≤ max(1, floor(T_a/4))`，且总探针时长不超过任务时限的 `ε`。
- 接触方向步长受限，避免戳坏物体/超力；自由空间可用大步长，接触附近自动降速。
- 探针次数受 UIP-15 预算约束：连续多次探针仍 `unknown`，则退回保守策略（不重做、只推进）。
- 离线为每个任务族选 `T_a`：接触密集任务 `T_a` 取小（如 4–8），远距离搬运取大（如 16–32）；**运行期不再改**。

### 4.3 与 v2 UIP-13 的关系

UIP-13 的“自适应块长”退役；UIP-19 是其合法替代：**反应性来自“块内动作节奏 + 探针”，不是来自“返回更短的块”**。

## 5. UIP-20 · PLA（Progress Ledger with Attribution，反事实进度账本）

### 5.1 账本结构

```text
每个计分步 s:
  w_s          # 来自 info.json 的 100 分权重
  pred_s       # §3 的关系谓词
  state_s ∈ {undone, ongoing, done, unknown}
  last_true_t  # 最近一次为真的时间
  cause_s      # intentional_undo / external_regression / action_failure / none
```

`Φ_t = Σ_s w_s · 1[state_s = done]`，并维护“历史最大 `Φ_max`”与“当前 `Φ_t`”。`Φ_t < Φ_max` 只说明发生了回退，**不直接等于外部撤回**；必须过 §1.3 的归因。

### 5.2 最小后缀重做

```text
被回退步集合 R = {s : cause_s = external_regression}
依赖闭包 D = {s' : s' 依赖 R 中某步} ∪ R
重做顺序 = 按技能图拓扑序；同层按 w_s / cost_s 降序
重做时把子目标设为 s 的前置谓词，而不是整任务从头开始
```

### 5.3 两种计分语义下的稳健性

- 若“曾经达成即入账”：重做只提升成功率，不额外加分 → 只重做**有后继依赖**的步；无依赖的回退可跳过。
- 若“终局状态结算”：所有回退都伤步骤分 → 在时间允许时重做无依赖步。
- 由于规则手册仍未取到（飞书纯客户端渲染），PLA 默认对两种语义都给出**可切换策略**，并在实验里分别报告。

## 6. 关键算法

### 6.1 FSCM 主循环（严格保持 `(T_a, …)` 形状）

```python
class FSCMPolicy:
    def __init__(self, vla, pas, vfs, skill_graph, T_a,
                 conf_thr=0.7, max_redo=2, probe_frac=0.25):
        self.vla, self.pas, self.vfs = vla, pas, vfs
        self.G, self.T = skill_graph, T_a
        self.conf_thr, self.max_redo = conf_thr, max_redo
        self.probe_p = max(1, int(T_a * probe_frac))

    @property
    def metadata(self):
        return {..., "action_chunk_size": self.T, ...}   # 握手期常量

    def reset(self):
        self.ledger.reset(); self.last_chunk = None
        self.prev_masks = None; self.redo = 0

    def get_action(self, obs):
        # 1) 双通道证据
        masks, parts = self.pas(obs)                       # UIP-17
        c, c_conf = self.vfs(obs, self.last_chunk)         # UIP-16
        # 2) 关系图与进度账本
        r = self.G.build_relations(masks, parts, obs.language)
        ev = self.ledger.update(r, c, c_conf, self.last_chunk,
                                self.G.current_skill)
        # 3) 归因与重做调度（UIP-20）
        skill, subgoal = self.G.decide(ev, self.ledger,
                                       max_redo=self.max_redo)
        # 4) 生成动作块（固定形状）
        A = self.vla.act(obs, masks, parts, c, skill, subgoal)  # (T, ...)
        # 5) 块尾探针（UIP-19），不改变形状
        A = self.probe_schedule(A, c, self.probe_p)
        self.last_chunk = A
        return A

    def probe_schedule(self, A, c, p):
        if c in ("free", "unknown"):
            return A
        # 在块尾 p 步插入“保持/轻推-保持/轻拉-保持”，其余动作不变
        A[-p:] = self.make_probe(A[-p:], c)
        return A
```

### 6.2 VFS 训练目标（事件级）

```python
def vfs_loss(batch):
    # batch 来自 Gazebo rollout（UIP-11/12）：含 contact/slip/mode 标签
    feat = encoder(batch.images, batch.q, batch.e, batch.g, batch.prev_action)
    contact = contact_head(feat)         # BCE
    slip    = slip_head(feat)            # BCE
    mode    = mode_head(feat)            # CE(6 类)
    load    = load_head(feat)            # 仅仿真辅助；真机不用绝对值
    L = bce(contact, batch.contact) + bce(slip, batch.slip) \
        + ce(mode, batch.mode) + 0.1 * smooth_l1(load, batch.force_q)
    L += domain_align(feat, batch.domain)   # 对抗/MMD
    return L
```

### 6.3 关系谓词示例（伪代码）

```python
def pred_closed_zipper(masks, parts, view_ids):
    slider = pick(parts, "zipper_slider")
    teeth  = pick(parts, "zipper_teeth")
    if slider is None or teeth is None:
        return UNKNOWN
    # 多视图投票：滑块是否在齿列顶端 + 两片布是否相接
    at_top = frac([proj(slider, v) near proj(teeth.top, v) for v in view_ids])
    joined = frac([mask_gap(teeth.left, teeth.right, v) < eps for v in view_ids])
    return TRUE if at_top > 0.7 and joined > 0.7 else FALSE
```

## 8. 合规、接口与工程约束

- **单模型合规**：动作头、分割头、VFS 头共享同一视觉主干；推理期不调用 SAM2/GroundingDINO/Florence。离线打标工具不计入提交物，但需在报告中披露。
- **动作硬约束**：返回形状必须严格 `(T_a, …)`；`meta.token` 每个 chunk 都要带；`control_space` 与动作键匹配；探针只改块内数值，不改形状。
- **观测硬约束**：`language` 只能 `[0]`；图像按键声明后才发送；`image_resize` 只能是已声明键；堆叠帧数直接影响 JPEG 带宽与延迟（UIP-08′）。
- **延迟与可信度**：分割头 + VFS 会增推理时间 → 共享主干、低分辨率 mask 头、批处理；多端口每端口状态隔离；探针/重做设预算（UIP-15），避免延迟尖峰。
- **评测语义未知**：步骤分是“曾经达成”还是“终局结算”仍未核实；PLA 对两种语义给可切换策略并分别报告。
- **数据空白**：公开数据无人为干扰、无力标签、无部件 mask；UIP-11/12 是唯一补标注路径，但存在仿真偏差。

## 9. 资源与时间线（粗排）

- 第 1–2 周：接口复现与可观测性审计；在 3 个代表任务（T26 插网线、T14 拧盖、T19 拉链）上手工验证“残差/夹爪/腕部光流”三路信号。

- 第 5–6 周：UIP-18 FSCM 状态机与 UIP-20 归因账本；UIP-19 探针在固定块上实现并做安全约束。
- 第 7–8 周：E201–E205 离线实验；UIP-08′ 多端口压测；`T_a` 扫描。
- 第 9 周起：预约真机，做 E206 的事件级校准与端到端验证。

## 10. 本轮最大风险 & 押注

**一句话**：最大风险是把“仿真里学到的接触事件”当成真机真值；一旦 VFS 自信地误报“被撤回”，FSCM 会反复重做，同时伤害成功率、步骤分和延迟可信度——所以 VFS 必须只作为**带拒识的软证据**，并以真机校准与预算护栏兜底。

**→ 押注：UIP-16 VFS × UIP-17 PAS 融合成 UIP-18 FSCM，由 UIP-19 在固定块内制造可观测接触、UIP-20 只重做最小依赖后缀。** 它把本轮两个灵感词都落在接口允许的范围内：语义分割解决“对哪个部件、什么关系”，虚拟力觉解决“刚刚是否真的接触/滑/卡”，两者共同填补 v2 在接触密集步骤上的最大盲区。
