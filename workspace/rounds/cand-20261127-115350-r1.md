## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（创新点挖掘 → 从「加模块」转向「挖缺口」）**
直觉：前两轮每轮都在加模块（I1 增广、I2 语料、I5 合成示教、I9 检索），但清单里没有一个量化的「下一铲挖哪里」的判据。创新点挖掘的正确形态不是头脑风暴更多点子，而是三件事：(a) 把排行榜要的分数（成功率主键 + 步骤分次键）拆成**计分缺口**；(b) 用消融把缺口**归因**到可干预的因（感知/接触/协同/时间/部署）；(c) 用「预期增益 × 覆盖 / 成本 × 风险」算**边际 ROI**，只挖 ROI 最高的格子，并用真机结果滚动校准。核心反直觉点：**创新点的稀缺不在「想不出」，而在「没算过哪个值得做」——一个能持续给出 ROI 排序的台账，比十个新点子更值钱。**

**灵感 2（协同控制 → 官方任务分类里被我们漏掉的第三类）**
直觉：官方把 32 任务定义为「抓取、放置与**双手协调**」（F26），而 v1.1 清单里 I1–I9 没有一个点正面建模臂-臂关系；官方 WLA 自己也叫「One Model Driven, Whole-Body Coordination」（F31）。但细看官方动作表示（F32）：左右臂各自预测「相对自身 ee 帧」的 6D 动作——**每臂是自洽的，臂与臂之间却没有显式的相对状态/监督目标**，协调只能从拼接向量里隐式学。于是大量 hold-and-act（一手扶、一手插/拧/倒/拉链）与 hand-off（换手）任务，协调关系全靠隐式学习，正是弱链。核心反直觉点：**双臂协同的关键不是「再加一个协调网络」，而是换一个把「整体运动」和「臂间相对关系」解耦的动作参数化——官方已经做了每臂自相对，缺的是跨臂的『中点帧』。**

**灵感 3（协同控制 → 要协同的不只是两只手，还有一栈控制器）**
直觉：v1.1 的 I3（伺服回退）、I4（干预停持）、I5（恢复）都是独立的 guard 模块；它们在同一 `get_action` 里可能同时想接管：伺服想修最后几厘米、干预想冻结、恢复想后撤。没有仲裁就会模式抖动、动作跳变，而官方明确记录延迟波动与动作统计规律用于可信度（F5/§6）。所以「协同控制」的第二层是**控制权威仲裁**：谁在什么条件下拥有控制权、切换要多长驻留、混合动作如何投影回安全包络。核心反直觉点：**guard 栈越多，越需要一个「减法」组件——仲裁器的价值不是加能力，而是让已有能力不互相打架。**

**三者统一**：创新点挖掘回答「为什么现在挖协同」（它是 ROI 最高的未开采格），协同控制回答「怎么挖」（I10 中点帧双臂参数化 + I11 控制权威仲裁）。本轮结论：**下一个最大分数洼地不在再多的数据增广，而在「臂与臂、控制器与控制器」之间的协同结构。**

## 2. 对前序痛点的增量修订

- P1（弱链支配）补充：hold-and-act 与 hand-off 类双臂任务是弱链中的结构性洼地，且官方明列为第三类（F26）。
- P2（泛化缺口）补充：中点帧把「整体位姿」与「臂间相对关系」解耦，位置轴（整体平移/旋转）变化不再扰动协调模式——位置泛化可被**结构化**降低，而不只靠增广。
- P3（人为干扰）补充：单臂扰动是双臂恢复的天然训练信号（扰动一只臂，要求另一只补偿），与 I5 合成示教天然合流。
- P5（时间压力）补充：协同失败（掉件、错位、换手掉手）是超时/卡死的主因之一。
- P6（部署风险）补充：guard 栈无仲裁会模式抖动，直接触碰官方可信度评估（F5）。
- 新增 **P9 协调缺口**：32 任务里大量双臂任务，但清单无显式臂-臂协调结构。
- 新增 **P10 创新挖掘缺口**：缺少量化的「计分缺口→归因→ROI」决策，导致按「点子」而非「缺口」投入。

## 3. 研究问题（本轮立项 Q9–Q12）

- **Q9（双臂耦合度量）**：如何仅从示教自动计算每任务的耦合指数 BCI，并据此把 32 任务分层为「强耦合/弱耦合/单手」？
- **Q10（协同动作表示）**：中点帧分解 (T_M, ξ) + 相位条件，能否在**单模型**内降低 14-DoF 联合学习难度、让换手连续、并提升位置/未见物品轴泛化？与官方「每臂自相对」表示如何兼容？
- **Q11（控制权威仲裁）**：如何在单个 PolicyService 内让 chunk/servo/hold/recover 协同——不抖动、不越界、不超时？「单模型」边界如何向组委会界定？
- **Q12（创新 ROI，元层）**：如何把「计分缺口 → 因果归因 → 边际 ROI」做成可滚动校准的挖掘台账，并用真机结果反过来校准离线 ROI 预测？

## 4. 设计原则（新增 PR6/PR7）

- **PR6 协同守恒律**：任何双臂动作必须显式保持或有意改变两臂相对位姿；臂间相对量是一等状态，不能只作为隐变量。
- **PR7 权威单调律**：控制权优先级固定为 安全 > 干预 > 伺服 > chunk；模式切换必须有驻留时间与滞回；任何混合动作必须先投影回安全包络再输出。
- PR5 数据杠杆律保留；PR1–PR4 保留（第 1 轮）。

## 6. 本轮最大风险

**一句话**：I10 的中点帧分解假设「示教里的臂间相对量 ξ 是平滑、可学的协调不变量」——若相当一部分双臂任务其实是「一只手基本静止、另一只手独立完成」，ξ 的方差主要来自无关的静止手抖动，强行建模反而给策略注入噪声；因此必须先用 BCI 与 ξ 的谱分析把「真协同」和「假协同」分开，再决定 I10 的覆盖范围，否则它会把 I3/I4 省下的自由度又还回去。

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2）

> 检索日期：2026-11-26（第 1 轮）、2026-11-27（第 2/3 轮）。来源见 §6。承接 v1.1：I1/I2/I5/I8/I9 深化，新增 I10/I11，I3/I4 降为 I11 控制器，**I7 裁撤**，I6 维持。清单只增改不重置。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I10 中点帧双臂协同参数化 ★★★★★（新，本轮核心）
- **动机**：官方把 32 任务定义为「抓取、放置与**双手协调**」（F26），但 v1.1 无任何臂-臂显式建模；官方动作虽是每臂自相对（F31/F32），臂间关系仍只能隐式学。hold-and-act 与 hand-off 类任务因此是弱链（P9）。
- **与现有方案差异**：官方/基线 = 左右臂各自预测「相对自身 ee 帧」的 6D，协调靠共享潜变量隐式猜。本点把双臂位姿重参数化为「中点帧 T_M（整体运动）+ 臂间相对 ξ（协调）」：T_M 管搬运/位置，ξ 管协调/换手。**这是同一策略的输出重参数化，不新增模型、不改接口**，输出仍转换回官方 `left/right_ee_pose_gripper_base` 动作键。
- **技术可行性**：高。观测已给双臂 ee 位姿（F30），ξ 可在推理期直接算；训练目标由数据 ee 轨迹精确构造；角色交换是 ξ→−ξ、T_M 不变的**精确对合**，可做等价增广。加一个耦合门 γ：低耦合任务自动退回每臂独立头，避免「假协同」注入噪声（本轮最大风险的对冲）。
- **所需资源**：BCI/ξ 谱离线计算 1 GPU 日；动作头改造 + 单元测试 2 人周；训练沿用 1×24GB LoRA 起步（F11）；真机 L2 见 §2。
- **落地步骤**：①32 任务实算 BCI 与 ξ 谱，产出分层表（§3）；②实现 `to_midpoint/from_midpoint/mid_targets` 与官方动作互转，做往返误差测试；③训练加中点帧头 + 每臂头 + 耦合门 γ；④角色交换等价性单测；⑤高 BCI 任务 L1/L2。
- **风险**：假协同（一手静止、另一手独立）→ 耦合门 + 分层表先验；SE(3) 中点对平移分量非严格测地 → 只要求「可逆 + 角色对合精确」，不依赖度量最优；换手处 ξ 连续但数值敏感 → 用双精度构造目标 + 限幅。

### I11 控制权威仲裁器 ★★★★（新，本轮集成层）
- **动机**：v1.1 的 I3（伺服）、I4（停持）、I5（恢复）是并列 guard 模块，同一 `get_action` 内可能同时想接管，导致模式抖动/动作跳变；官方记录延迟波动与动作统计规律用于可信度（F5/§6），抖动是直接风险（P6/P9）。
- **与现有方案差异**：多数队伍把 guard 写成 if-else 补丁，谁后写谁生效。本点把控制权形式化为**优先级 + 滞回 + 驻留 + 安全投影 + deadline** 的仲裁器：安全 > 干预 > 伺服 > chunk，模式切换有最小驻留，混合动作先投影回安全包络，超时降级为 hold。
- **技术可行性**：高（纯工程 + 状态机）。不改模型，只在服务层调度；可在本地 stub 用日志轨迹离线仿真验证。
- **所需资源**：1 人周工程；无额外 GPU；复用 I6 的队列/健康探针。
- **落地步骤**：①定义安全包络 E（关节限位/速度/双臂最小距离/夹爪界）；②实现优先级状态机 + 滞回/驻留；③chunk 异步缓存 + 超时 hold；④本地 stub 故障注入（并发/延迟/越界）；⑤真机 A/B。
- **风险**：单模型边界解释（安全/停持模块是否算「多模型」）→ 书面求证，降级方案是「纯规则优先级 + 安全投影，无学习组件」；仲裁过保守 → 冻结率上升，用驻留与 TTL 上限约束。

### I1 v3 考纲校准五轴增广引擎 ★★★★★（深化）
- **动机/差异**：同 v2（按官方考纲校准五轴）；本轮加**角色交换/镜像增广**：在表示层对双臂数据做 (L,R) 交换，ξ→−ξ、夹爪互换，作为精确等价样本，直接扩双臂数据并强化 I10 的角色对称性。
- **可行性/资源**：高；图像层镜像只在机械臂近似对称时用，表示层交换无条件可用。
- **落地步骤**：在 I10 目标构造管线里加 `swap_roles(ep)`；与背景/干扰物轴解耦，单独消融。

## 1. 关键推导与伪代码

### 1.1 双臂耦合指数 BCI 与任务分层（I10 的前置门禁）

**直觉**：先分清「真协同」与「假协同」。真协同 = 两只手在同一段时间都参与、且臂间相对量 ξ 平滑可学；假协同 = 一只手基本静止，另一只手独立完成，此时 ξ 的方差主要来自静止手抖动。BCI 就是这把筛子。

**定义**：对一条示教 episode，令夹爪状态 g_L(t), g_R(t)，ee 位姿 T_L(t), T_R(t)（base 系），速度 v_L(t), v_R(t)。用每 episode 的 2-means 把夹爪值分成开/合两态 c_L(t), c_R(t) ∈ {0,1}（避免依赖开合方向约定）。定义

- 接触耦合：BCI_contact = (1/T) Σ_t c_L(t)·c_R(t)
- 运动耦合：BCI_kin = (1/T) Σ_t 1[v_L(t)>ε ∧ v_R(t)>ε ∧ |corr_W(v_L,v_R)|>κ]
- 臂间相对：ξ(t) = log(T_L(t)^{-1} T_R(t)) ∈ R^6
- ξ 平滑度：S = 1 / (1 + mean_t ||ξ̈(t)||)
- 单臂静止占比：s = fraction{ t : min(v_L,v_R)<ε < max(v_L,v_R) }
- 协调信噪比：CSNR = 低频功率(ξ) / 总功率(ξ)

综合 BCI = w1·BCI_contact + w2·BCI_kin，并把 (BCI, S, s, CSNR) 一起报告。分层阈值不拍脑袋：对 32 任务的 BCI 向量做 2-means，高簇 = A（强耦合），中簇 = B（弱耦合），低簇 = C（单手/顺序）。

```python
def bci(ep, eps=1e-3, W=15, kappa=0.3):
    cL, cR = two_means_closed(ep.gripper_L), two_means_closed(ep.gripper_R)
    vL, vR = ee_speed(ep.TL), ee_speed(ep.TR)
    bci_c = mean(cL * cR)
    bci_k = mean((vL > eps) & (vR > eps) &
                 (abs(sliding_corr(vL, vR, W)) > kappa))
    xi = log_se3(inv(ep.TL) @ ep.TR)              # (T, 6)
    S = 1.0 / (1.0 + mean(norm(diff(xi, n=2), axis=1)))
    s = mean((minimum(vL, vR) < eps) & (maximum(vL, vR) >= eps))
    csnr = lowfreq_power(xi, W) / (total_power(xi) + 1e-9)
    return dict(bci_c=bci_c, bci_k=bci_k, bci=0.5*bci_c+0.5*bci_k,
                S=S, s=s, csnr=csnr, xi=xi)
```

**真协同判据**（进入 I10 覆盖）：BCI 高 ∧ S 高（ξ 平滑）∧ s 不极端（不是一只手长期静止）。若 BCI 高但 s 很高，标为「假协同候选」，耦合门 γ 置 0，退回每臂独立头。

### 1.2 中点帧双臂协同参数化（I10 核心）

**直觉**：官方让每只手臂各自「相对自己」预测动作，这解决了单臂的尺度/位置泛化，却把「两只手怎么配合」留给了隐变量。我们把双臂位姿拆成两个正交量：**整体在哪（T_M）** 与 **两手相对多远/多转（ξ）**。前者负责搬运与位置泛化，后者负责协调与换手。

**定义**：设 T_L, T_R ∈ SE(3)（base 系）。令

- ξ = log(T_L^{-1} T_R) ∈ se(3) ≅ R^6
- T_M = T_L · exp(½ ξ)（Lie 群中点帧）

则 T_M^{-1} T_L = exp(−½ ξ)，T_M^{-1} T_R = exp(+½ ξ)：两臂关于中点对称。**角色交换 (L,R)→(R,L) 时 ξ→−ξ、T_M 不变**，是精确对合：

```
T_M' = T_R · exp(½ log(T_R^{-1}T_L)) = T_R · exp(−½ξ) = T_L·exp(½ξ) = T_M
```

于是把动作目标从「(a_L, a_R)」重参数化为「(ΔT_M, Δξ)」：

- ΔT_M = log(T_M(t)^{-1} T_M(t+1))：整体双臂运动
- Δξ = ξ(t+1) − ξ(t)：臂间协调变化

推理时反解回官方动作键：

```
T_M(t+1) = T_M(t) · exp(ΔT_M)
ξ(t+1)   = ξ(t) + Δξ
T_L(t+1) = T_M(t+1) · exp(−½ ξ(t+1))
T_R(t+1) = T_M(t+1) · exp(+½ ξ(t+1))
a_L = rel6(T_L(t)^{-1} T_L(t+1))      # 官方 left_ee 6D（相对 xyz + rotvec）
a_R = rel6(T_R(t)^{-1} T_R(t+1))      # 官方 right_ee 6D
```

（`log_se3/exp_se3` 只用于中点帧的 Lie 群构造；官方动作键按文档 §3.2 用 `rel6` = 相对平移 + 旋转向量。）

**关键性质**：这是同一策略的**输出重参数化**，不新增模型、不改评测接口；输出仍转换回官方 `left/right_ee_pose_gripper_base`。角色交换增广是精确等价（ξ 取负、夹爪互换），可直接扩数据。换手处 ξ 连续，无需离散角色变量。

```python
def to_midpoint(TL, TR):
    xi = log_se3(inv(TL) @ TR)
    TM = TL @ exp_se3(0.5 * xi)
    return TM, xi

def from_midpoint(TM, xi):
    return TM @ exp_se3(-0.5 * xi), TM @ exp_se3(0.5 * xi)

def mid_targets(TL0, TR0, TL1, TR1):
    TM0, xi0 = to_midpoint(TL0, TR0)
    TM1, xi1 = to_midpoint(TL1, TR1)
    dTM = log_se3(inv(TM0) @ TM1)       # 整体运动
    dxi = xi1 - xi0                      # 臂间协调变化
    return dTM, dxi

def mid_to_actions(TL0, TR0, dTM, dxi):
    TM0, xi0 = to_midpoint(TL0, TR0)
    TM1 = TM0 @ exp_se3(dTM)
    TL1, TR1 = from_midpoint(TM1, xi0 + dxi)
    aL = rel6(inv(TL0) @ TL1)
    aR = rel6(inv(TR0) @ TR1)
    return aL, aR                        # 与官方动作键一一对应

def swap_roles(ep):                      # 精确等价增广
    ep2 = copy(ep)
    ep2.wrist_L, ep2.wrist_R = ep.wrist_R, ep.wrist_L
    ep2.TL, ep2.TR = ep.TR, ep.TL
    ep2.gL, ep2.gR = ep.gR, ep.gL
    ep2.xi = -ep.xi                      # T_M 不变
    return ep2
```

**耦合门 γ**：设每臂独立头输出 a_perarm、中点帧头输出 a_mid（均已转成官方动作），最终

```
a = (1 − γ) · a_perarm + γ · a_mid,   γ ∈ [0,1]
```

γ 可由任务级 BCI 先验给（高 BCI=1，低=0），也可由一个小门控网络从 (指令嵌入, BCI 特征) 学。γ=0 时完全退回官方表示，保证 I10 不会伤低耦合任务（本轮最大风险的对冲）。相位 φ 由 I5 进度头提供，作为协调头的条件输入；高 BCI 任务的 ξ(φ) 往往近似一条曲线，相位条件把「学 14-DoF 联合动作」降成「学一条协调曲线」。

### 1.3 控制权威仲裁器（I11）

**直觉**：guard 栈是「加法」，仲裁器是「减法」。谁在什么条件下拥有控制权、切换要多长驻留、混合动作怎么不越界——这三件事决定 guard 栈是增益还是抖动源。

**定义**：控制器集合 C = {chunk, servo, hold, recover}，每个给出 (a_c, conf_c, valid_c)。安全包络

```
E = { a : q_min ≤ q ≤ q_max, |q̇| ≤ v_max, d(E_L,E_R) ≥ d_min, gripper ∈ [0,1] }
```

优先级固定为 safety > hold > servo > chunk。模式切换用「进入阈值 θ_in / 退出阈值 θ_out」的滞回 + 最小驻留 d_min。仅当伺服输出是「增量修正」且处于接触相位时，允许软混合 a = (1−λ)a_chunk + λ a_servo（λ = λ_max·conf_servo）；否则硬切换。输出前投影 Π_E(a)；若投影改动超过 ε_safe，则否决为 hold。

```python
class AuthorityArbiter:
    PRIORITY = ["safety", "hold", "servo", "chunk"]

    def step(self, obs, prop):                  # prop[c] = (a_c, conf_c, valid_c)
        mode = self._select_mode(prop)          # 滞回 + 驻留
        if mode == "servo" and prop["servo"].valid:
            lam = self.lam_max * prop["servo"].conf
            a = (1 - lam) * prop["chunk"].a + lam * prop["servo"].a
        else:
            a = prop[mode].a
        a_proj = project_envelope(a)            # 关节/速度/双臂距离/夹爪
        if norm(a_proj - a) > EPS_SAFE:
            mode, a_proj = "hold", self.hold_action(obs)
        if mode == "chunk" and self._chunk_stale():
            mode, a_proj = "hold", self.hold_action(obs)
        return a_proj, mode

    def _select_mode(self, prop):
        # 高优先级且 valid 的控制器接管；进入/退出阈值分离防抖
        for c in self.PRIORITY:
            if prop[c].valid and prop[c].conf > self.theta_in[c]:
                if c != self.mode and self._dwell_ok(c):
                    self.mode = c
                break
        return self.mode
```

**要验证的性质**：(P1) 安全不变式——任何输出都在 E 内；(P2) 无抖动——模式切换满足驻留且进入/退出阈值分离；(P3) 有界延迟——chunk 异步、超时 hold，p99 < 40ms；(P4) 权威单调——安全 > 干预 > 伺服 > chunk。

### 1.4 创新 ROI 台账（I8 v3，元层「创新点挖掘」）

**直觉**：把「下一个做什么」从品味问题变成排序问题。每个候选创新算一个边际 ROI，真机结果回填校准，形成会增值的决策资产。

**定义**：排行榜主键是成功率、次键是步骤分，故用标量化 J = success + λ·step/100（λ 小，例如 0.1）。对候选创新 i：

```
ROI_i = (ΔJ_i · coverage_i) / (cost_i · risk_i)
```

- ΔJ_i：该点影响的每任务期望增益（用 L0 代理 + 注册表校准）
- coverage_i：受影响的计分 episode 占比（32 任务 ×10 = 320 次）
- cost_i：人周 + GPU 日 + 真机 episode
- risk_i：增益落空概率（负迁移/合规否决/延迟超限）
