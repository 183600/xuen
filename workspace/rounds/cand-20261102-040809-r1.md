# 第 13 轮（新灵感循环第 1 轮）· RAG-AC：把「检索增强」从找目标图推进到「参考轨迹 + 在线辨识 + 自适应增益」——30% 的天花板可能是执行层的分布漂移，不只是最后 3 厘米

> 检索/复核日期：**2026-11-02（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮三个灵感词是「自适应控制」「具身智能大模型」「检索增强生成」。本轮不推倒第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是补上它们共同缺的一层：**在线自适应**。第 12 轮假设「在数字孪生里标定一次、固定伺服」，但评测跨 N 台机器人、RTT 会变、桌面高度/光照/物体位置每次不同；静态标定会在评测中过期。

## 0. 先给结论：不是「再大一点」，是「再适应一点」

截至 2026-11-02，官网榜单仍是 8 个模型：MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。榜单没有更新；`runs.html` 现在列出 256 行（8×32），但详情视频仍是「测试视频占位，后续可替换为真实视频文件」，步骤分与成功率仍满足 `step ≈ k_model × success`（R²>0.999999），任务成功率仍出现 27.29%、27.85% 这类非 10% 整数倍。**结论不变：29.7% 是赛事方给的预览上限/难度信号，不是可复现的 SOTA。** 但「榜首不到 30%」这个事实仍值得当作设计约束。

上一轮 CHUNK-SERVO 的判断是「最后 3 厘米开环」。本轮先做了一次真实数据核验，发现这个判断只对了一半：

- HangCup 前 719 条演示里，右臂初始 EE 位姿的 xyz 标准差约 **[5.3, 4.3, 2.5] cm**，yaw 标准差 **0.25 rad**。位置泛化不是「厘米级扰动」，而是「十厘米级 + 大角度」。
- 只用初始状态做 1-NN 检索，全轨迹 RMSE 约 **70 mm**；而「所有演示的平均轨迹」也有 **71 mm**，随机参考是 **102 mm**。**naive RAG ≈ 平均值，不够。**
- 但在轨迹中程用「当前 EE + 夹爪 + 相位」检索，未来窗口（重采样 30 点）RMSE 从 **84→42 mm（p=0.3）、78→49 mm（p=0.5）、57→28 mm（p=0.7）**，在 73–76% 的 episode 上优于平均轨迹。**检索必须相位化、状态化、在线化。**
- 数据里 `action` 到下一帧 `state` 的有效跟踪增益按轴差异很大：x≈0.39、y≈0.35、z≈0.12、yaw≈0.34；z/roll/pitch 的 R² 只有 0.21/0.51/0.16。**一个全局伺服增益是错的，至少应按轴/相位辨识。**

所以本轮押注 **RAG-AC**：

> 用官方 WLA 作为唯一学习模型；用 33k 成功演示做**相位感知的参考轨迹检索**；用同一 WLA 采样多个候选 chunk，用检索到的参考分布做**确定性重打分**；在 chunk 边界用**在线系统辨识**估计每轴有效增益/延迟，调度自适应增益；chunk size 在提交时固定（接口不允许在线改），但增益、参考、候选选择在线变。

一句话：**把「检索一张目标图」升级为「检索一段参考轨迹」，把「固定伺服」升级为「chunk 级在线辨识 + 自适应增益」，把「模型输出什么就执行什么」升级为「同模型多采样 + 检索参考重打分」。**

三个可验证创新点：

1. **RAG-Ref（相位感知参考轨迹）**：从 33k 演示检索同任务、同相位、同相对位姿的未来 H 步轨迹分布；不是单张 keyframe，也不是单条最近邻。用 G1/G2 验证「中程检索 > 初始检索 > 平均轨迹」。
2. **RAG-AS（检索增强的动作选择）**：同一 WLA 采样 N 个候选 chunk；用参考分布的 Mahalanobis 距离 + 平滑度 + 相位一致性做确定性打分；不加载第二个学习模型。用 G3 验证 top-1 vs top-N、N=2/4 的收益/延迟。
3. **AC-SysID（chunk 级自适应控制）**：在 chunk 边界用最近窗口辨识每轴 `(a,d)`（有效增益/延迟），按稳定域调度 `K_p/K_d`，做 Smith/卡尔曼延迟补偿；可选跨 trial 低维参数记忆（合规待确认）。用 G4/G5 验证固定增益 vs 自适应增益在 0/100/200ms 延迟和 ±40% 增益失配下的稳定域。

三个灵感词怎么落地：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **自适应控制** | chunk 边界在线辨识 `(a,d)`；按轴/相位调度增益；延迟补偿；投影/死区/回退 | 不做 30Hz 广域网伺服；不在线改 chunk size（接口不允许）；不做第二个学习策略 |
| **具身智能大模型** | 官方 WLA-1.0 6B 做唯一策略；LoRA 单适配器覆盖 32 任务；同 checkpoint 多采样 | 不从零训 6B/14B；不做 per-task LoRA/多模型混合 |
| **检索增强生成** | 33k 演示 → 相位参考分布；检索结果用于候选重打分/参考/恢复 | 不做「初始状态 1-NN」这种 naive RAG（先导实验已证伪）；不让检索输出直接当动作 |

## 1. 本轮新核实/复核的事实（只列会改变方案的）

### 1.1 赛事身份与规则（A）

- 官网、挑战赛页、提交仓库均指向宇树；检索到的官方页面未指向其他 UniBot，按 Unitree 展开。
- 规则：单模型完成全部 32 任务；每任务 10 次；5 类泛化各 2 次（位置/干扰物/背景/未见物品/人为干扰）；单次上限 180s；排名先总平均成功率，再总平均步骤分，再更早提交；N 台机器人、8765 起连续端口；另有单任务不计分测试通道。
- 提交方式：注册账号 → 提交模型 → 在 profile 页预约评测时段。评测时段是有限资源，必须按「有限次数」规划，不能假设无限 A/B。

### 1.2 提交接口（A，本轮最重要的修正）

- 四路 RGB 480×640；本体 EE 位姿/夹爪/lower_body/language；没有 depth、camera_info、force/torque、tactile。
- **`action_chunk_size` 在 handshake 时固定，每次 `get_action` 必须返回同样长度；evaluator 执行完整个 chunk 才会再次调用。** 这意味着第 12 轮说的「RTT 高就把 H_c 调到 8」只能作为**提交前**选择，不能在线改。所谓「自适应 horizon」在官方接口下不成立；本轮把它改为「固定 chunk + 自适应增益/参考」。
- 反馈周期 `T_fb = H/f_c + τ`；H=5、30Hz、τ=50ms → 217ms；τ=150ms → 317ms。H 必须按实测 RTT/控制频率离线选。
- `ee` 模式动作是**绝对目标位姿**（base 系 xyz+rpy）；WLA 输出相对 EE，需要 compose。`pivot` 7 维语义数据集 README 给出 `vx,vy,angle_z,pivot_3..5,height`；先保持 pivot 常数，只验证双臂。

### 1.3 数据（A）

- 32 数据集合计 **33,276 episodes / 18,282,246 frames / 169.28h @30fps**（本轮逐数据集复核，与上轮一致；官网写 32,000 是约数）。
- 数据集**没有 language 字段**，32 任务是 32 个独立数据集；线上 API 有 language。RAG 必须先用任务路由（确定性关键词/任务 ID）选 shard，再检索。
- 四路视频；头双目有内参/基线 58.2526mm/rectified；腕部相机无内参。
- 动作/状态字段齐全；`pivot` 高度在 HangCup 中几乎恒为 0.738，说明桌面任务下身体基本不动，可先冻结。

### 1.4 官方基座与 LoRA（A）

- **UnifoLM-WLA-1.0**：6B，约 2500h 真机，64 任务，54 维动作/60 维状态，默认 `chunk_size=30`、`target_fps=30`，4 步扩散；冻结 VLM 微调 action head 单张 24GB 可跑。
- **2026-09-29 新增 LoRA**：VLM 和/或 action model 都可 LoRA；适配器只有 `lora_*` 张量，适合分发；这是本轮「一个模型覆盖 32 任务」的关键新事实。
- 官方 WLA 是否已覆盖挑战赛 32 任务、`pivot` 是否与挑战赛一致，仍未核实；必须在单任务通道实测。

### 1.5 榜单取证（A+B）

- 榜单 8 模型分数未变；`leaderboard_data.json` 的 `generated_from=gen_leaderboard.py`；8×32 回归 R²>0.999999，最大残差<0.006；跨模型任务成功率平均 off-diagonal 相关 0.0975；任务成功率非 10% 整数倍；详情页视频占位。
- `runs.html` 现在列出 256 行，但仍是同一套合成指标；不能当真实失败分布。
- 结论：只把榜单当「难度信号/预览上限」，不从任务排名挖创新点。

### 1.6 近期工作与本轮差异（A，arXiv 2026-10）

- **RA-VLA**（2608.25585，ICML 2026）：检索增强 VLA 做 test-time adaptation，行为对齐检索 + grounded execution。说明「RAG-VLA」本身不新；我们要做的是**控制层自适应 + 参考轨迹 + 候选重打分**，不是再做一个 RAG-VLA。
- **PHASE**（2609.30889，IROS 2026）：用触觉做相位分割 + 相位一致检索，未见初始位置 +30pp。挑战赛没有触觉，但「相位一致检索」可用视觉/本体代理。
- **PaceVLA**（2610.25961）：学习自适应时间量化/执行模式；说明「自适应 horizon」是热点，但它是学习路由器，我们是固定 chunk + 控制层自适应，避免第二个模型。
- **VLA-Stem**（2610.37378）：用 RL 训一个轻量 Stem 策略改执行；效果强，但这是第二个学习模型，单模型规则下有合规风险。我们的替代是确定性自适应控制器。
- **JevVLA**（2610.35010）：80k 参数能量模型做候选选择/动作修正；说明「轻量打分器」可行，但我们用非参数检索分数，进一步降低合规风险。
- **SaiVLA-JEPA**（2610.38508）：context adaptation 有系统级收益，parameter adaptation 没有稳定优势；提醒我们：**优先检索/上下文自适应，参数自适应只做低维控制参数**。
- **StateMem / TTT-RM**（2609.22684 / 2610.04701）：在线记忆/测试时训练；我们不做权重更新，只做控制参数。
- **DEED**（2610.40430）：演示扩展 + 执行设计（IK/夹爪映射/闭环重规划）在 MetaFine 85.55%；支持「执行层设计」是主要边际收益。
- **JEDI**（2610.40356）：演示压缩/检索用于 in-context imitation；支持「检索要保留执行细节」。
- **CoRAct**（2610.39543）：reasoning-action 后果对齐；与我们互补，不做。
- **CoAWM**（2610.40401）：跨具身/频率的连续动作世界模型；长期方向，不做。

## 2. 诊断：三个「静态」叠在一起

1. **静态策略**：一个 checkpoint 面对 5 类泛化；训练分布不等于评测分布。
2. **静态标定**：第 12 轮的相机外参/TCP/增益/RTT 在数字孪生里标一次；评测跨 N 台机器人，装配误差、相机位置、桌面高度、网络延迟都会变。
3. **静态执行**：chunk 固定、动作开环；chunk 内没有新观测；VLA 输出什么就执行什么。

第 12 轮解决了「chunk 内开环」，但没有解决「跨机器人/跨 trial 的分布漂移」。本轮把执行层做成**在线自适应**：

```text
观测 → 任务路由 → 相位估计 → 参考检索 → VLA 采样 N 个 chunk
     → 检索参考重打分 → 选 1 个 chunk → 在线辨识 (a,d)
     → 自适应增益/延迟补偿 → 输出固定长度 chunk
     → 下一 chunk 边界再更新
```

## 3. 方法：RAG-AC

### 3.1 总架构

```text
Evaluator (N ports 8765..)
        │ websocket: obs / fixed-length action chunk
        ▼
Per-port PolicyService (CPU)
  ├─ task router (32-way, deterministic)
  ├─ phase detector (gripper/velocity/residual/visual motion)
  ├─ RAG-Ref: demo index → reference distribution
  ├─ RAG-AS: score N WLA candidates against reference
  ├─ AC-SysID: estimate per-axis (a,d), schedule gains
  ├─ recovery: edit/contact residual → retrieve/replan
  └─ action adapter (WLA 54D → API 21D)
        │ async, batched, N samples
        ▼
Shared WLA server (GPU): UnifoLM-WLA-1.0 + one LoRA
```

- 每个端口独立 `reset()`、独立相位/检索/控制器状态。
- 共享 WLA server 只有一份权重；LoRA 只有一个适配器，不按任务切换。任务由 language/task router 条件化。
- 检索索引只读、可共享；每端口只维护查询缓存和控制器参数。

### 3.2 相位感知参考库

相位定义：`approach → grasp → transport → align → insert-or-hang → release`。用确定性检测器，不引入第二个学习模型：

```text
g_t = 夹爪开合（0=close, 4.5=open）
v_t = ||EE 线速度||
r_t = ||action_ee - next_state_ee||   # 动作-状态残差，接触代理
m_t = 腕部/头部图像帧差运动能量
φ_t = 规则(g_t, v_t, r_t, m_t, 上一相位)
```

每个 episode/相位存：

```text
(task_id, phase, progress_bin,
 T_task_ee(k),            # 任务坐标系下的 EE 相对位姿
 a(k:k+H),                # 未来 H 步动作
 I_wrist(k),              # 可选视觉描述子
 q(k))                    # 质量权重
```

质量权重不是「成功/失败」（数据全是成功演示），而是：

```text
q = 1 / (1 + α·tracking_residual + β·jerk + γ·phase_disagreement)
```

这样检索不会优先选「动作抖、跟踪差」的演示。参考不是单条轨迹，而是同一 `(task, phase, progress_bin)` 下的加权均值/协方差。

### 3.3 RAG-Ref：检索一段参考，而不是一张图

```text
z_t = [T_task_ee(t), g_t, φ_t, progress_t, visual_descriptor_t]
candidates = index.filter(task=task_id, phase=φ_t, |progress-progress_t|<δ)
d_i = ||z_t - z_i||_Σ
w_i = softmax(-d_i / τ) * q_i
μ_ref = Σ w_i x_ref_i
Σ_ref = Σ w_i (x_ref_i-μ_ref)(x_ref_i-μ_ref)^T + Σ_0
confidence = f(top1 margin, inlier count, trace(Σ_ref))
```

- 任务/相位过滤优先于外观，避免「插网线」匹配到「拔网线」。
- 低置信度 → 回退 VLA 开环或头双目 PBVS；不硬做。
- 参考只用于「跟踪/打分/恢复」，不直接把检索到的动作下发给机器人。

先导实验的教训（见 §4）：**初始状态 1-NN ≈ 平均轨迹；必须用到中程状态和相位。** 这不是一个实现细节，而是 RAG 能否有用的分水岭。

### 3.4 RAG-AS：同模型多采样 + 确定性重打分

```text
candidates = [WLA.sample(obs, noise_i) for i in 1..N]   # 同一 checkpoint
for a in candidates:
    y(a) = compose_to_absolute(a, obs)                  # H 步 EE 轨迹
    J(a) = (y-μ_ref)^T Σ_ref^{-1} (y-μ_ref)
         + λ_s ||Δ² y||²
         + λ_φ 1[φ(y) ≠ φ_t]
         + λ_g ||gripper_timing(a) - gripper_timing_ref||²
pick a* = argmin J
if min J > θ_J: fallback to WLA top-1 or hold/replan
```

- 打分器没有学习权重；所有项都是几何/统计量。
- N=2 默认；N=4 只在离线验证且 GPU 有余量时用。WLA 6B 单次推理若 80–120ms，N=2 叠加检索/RTT 已接近 200ms；必须异步、批处理，并测 p99。
- 这一步直接利用「生成模型可以采样」这一事实，把 RAG 从「给模型看参考」变成「在候选里选最像成功演示的」；不需要第二个模型。

### 3.5 AC-SysID：chunk 级在线辨识 + 自适应增益

在 chunk 边界（每 H 步）观测 `x_k`，用最近窗口拟合每轴一阶有效模型：

```text
x_{k+1} = x_k + a ⊙ (u_{k-d} - x_k) + w_k
```

- `a` 是**有效闭环增益**（包含低层控制器、H 步保持、机械柔顺），不是物理电机增益；只在局部有效。
- `d` 是 chunk 级延迟（0…D_max），用网格搜索 + 最小二乘/鲁棒 RLS 估计。
- 每轴独立估计：x/y/z/roll/pitch/yaw 的 `a` 差异很大（先导实验已证），不能共享一个标量。

控制：

```text
e_k = x_ref(k) - x_k
u_k = u_k^VLA + K_p(φ, â) e_k + K_d(φ, â) ė_k
K_p = k_p^0(φ) / â,  K_d = k_d^0(φ) / â
clip(K, K_min, K_max); projection; dead-zone
```

- `k^0(φ)` 来自离线仿真稳定域表；接触段法向增益乘 0.3–0.5，切向保留。
- 延迟补偿：用 `d̂` 做 Smith/卡尔曼预测；`d̂` 大时降增益，不追高。
- 先做**间接自适应**（辨识 + 增益调度），它比直接 MRAC 更稳、更可解释；MRAC 作为可选升级。

### 3.6 固定 chunk 合同（对第 12 轮的修正）

- `H` 在提交时固定；不能在线改。选 `H∈{3,5,8}`：
  - H=3：反馈快，但 RTT 占比高、VLA 调用频繁；
  - H=5：默认，167ms 执行块；
  - H=8：自由空间/长程，267ms 执行块。
- 用实测 `f_c` 和 `τ` 选 H；不要假设 30Hz 和 50ms RTT。
- chunk 内没有新观测；所有自适应都发生在 chunk 边界（6.7Hz @H=5），不是 30Hz。
- 如果评测端允许不同提交用不同 chunk size，就把它当**提交级超参数**扫；不能当在线变量。

### 3.7 恢复与可选跨 trial 自适应

恢复：

```text
if ||e|| > ε or edit_score > θ_e:
    hold; re-localize; retrieve recovery segment
    if match: resume with conservative gain
    else: request VLA replan with new image + language
```

跨 trial（可选，合规待确认）：

- 每个端口、每个任务维护一个低维参数向量 `θ_task`（每轴增益、接近偏移、夹爪时序），不更新任何网络权重。
- 每个 episode 结束（`reset()`）用自监督跟踪误差/最终视觉结果更新 `θ_task`；投影到安全集。
- 这是「 episodic adaptive control」，不是第二个模型；但「是否允许利用前几次 trial」必须邮件确认。若不允许，`ADAPT_TRIALS=0` 一键关闭。

## 4. 先导实验：真实数据 + 仿真（本轮新增）

### 4.1 数据与口径

- 数据：HangCup `file-000.parquet`，719 episodes / 130,565 frames；平均 181.6 帧/条（6.05s）。
- 只用右臂（HangCup 的右夹爪有明显开合；左夹爪几乎常开）。
- 轨迹对齐：把每条 episode 的 EE xyz 按归一化时间重采样到 100 点；检索实验用未来窗口（重采样 30 点）。
- 这是**单任务先导**，不是 32 任务结论；所有数字只用于方向判断。

### 4.2 初始位姿分布

| 量 | 均值 | 标准差 | 范围 |
|---|---:|---:|---:|
| x (m) | 0.2506 | 0.0531 | 0.1308–0.3581 |
| y (m) | -0.2856 | 0.0433 | -0.3665–-0.1517 |
| z (m) | 0.0903 | 0.0248 | 0.0609–0.1862 |
| yaw (rad) | 0.2417 | 0.2532 | — |

位置泛化的实际幅度是**十厘米级**；这支持「在线重定位/参考检索」而不是「固定轨迹」。

### 4.3 检索：初始状态不够，中程 + 相位才有效

| 检索方式 | 全轨迹 RMSE（100 点） |
|---|---:|
| 所有演示平均轨迹 | 71.4 mm |
| 初始状态 1-NN | 69.9 mm |
| 随机参考 | 101.9 mm |

初始状态 1-NN 只比平均轨迹好 1.5mm，基本等于「没检索」。再看中程（上表是全轨迹 100 点；下表是未来窗口 30 点，数值不可直接相减）：

| 进度 p | 未来窗口基线（30 点） | 相位+状态 1-NN | 优于基线的 episode 比例 |
|---:|---:|---:|---:|
| 0.3 | 84.3 mm | **41.6 mm** | 76% |
| 0.5 | 77.5 mm | **48.6 mm** | 73% |
| 0.7 | 57.4 mm | **27.9 mm** | 73% |

结论：**RAG 的价值不在「找到同一起点」，而在「找到同一相位/同一状态的未来」**。这也解释了为什么只做 keyframe 目标图不够：目标图不含「接下来 H 步怎么走」。

### 4.4 top-5 oracle：重打分有 8–16mm 的空间

| 进度 p | top-1 | top-5 最优（oracle） | 差距 |
|---:|---:|---:|---:|
| 0.3 | 41.6 mm | 28.8 mm | 12.9 mm |
| 0.5 | 48.6 mm | 32.2 mm | 16.5 mm |
| 0.7 | 27.9 mm | 19.7 mm | 8.2 mm |

top-5 里经常有比 top-1 好得多的参考；这支持 RAG-AS 的「候选重打分」，而不是只取最近邻。注意：oracle 是上界，真实收益取决于打分器质量；这是 G2/G3 要验证的。

### 4.5 动作-状态跟踪：每轴增益不同

对 `Δx_t = a·(u_{t-d} - x_t)` 做最小二乘，d=0 时：

| 轴 | 有效增益 a | R² |
|---|---:|---:|
| x | 0.388 | 0.713 |
| y | 0.348 | 0.839 |
| z | 0.115 | 0.209 |
| roll | 0.253 | 0.510 |
| pitch | 0.070 | 0.162 |
| yaw | 0.343 | 0.900 |

动作-状态误差 RMS：z 约 **16.0 mm**、pitch 约 **0.051 rad**；x/y 约 4–7mm。**高度和俯仰是最不听话的轴，也是插入/悬挂最容易失败的轴。** 这直接支持「按轴辨识 + 按轴调度增益」，而不是一个全局 `K_p`。

### 4.6 延迟/增益仿真：固定增益在 200ms 延迟下会失稳

1D 双积分器，dt=1/30，2.5s 最小 jerk 参考；固定增益按 d=0 调（kp=64, kd=16）：

| 延迟 | 固定增益 RMSE | 最优稳定增益 (kp,kd) | 最优 RMSE |
|---:|---:|---:|---:|
| 0 ms | 1.4 mm | (32, 2) | 0.45 mm |
| 100 ms | 118.9 mm | (16, 12) | 3.3 mm |
| 200 ms | 失稳 | (4, 2) | 14.5 mm |
| 300 ms | 失稳 | (4, 2) | 25.0 mm |

在线辨识：对 `(a,d)` 做 0…12 帧网格搜索 + 最小二乘；无噪声时精确恢复；加 10% 加速度噪声后，测试的 `(g,d)=(1.0,6),(1.4,3),(0.6,6),(1.0,0)` 仍全部 top-1 正确（估计值 1.001/1.371/0.600/0.970，延迟全对）。这说明「在线辨识延迟/增益」在原理上可行，但真实 G1 的低层控制器远比双积分器复杂，必须用 G3/G4 验证。

### 4.7 先导实验的边界

- 只用了 HangCup 的前 719 条；没有解码视频，没有视觉描述子。
- 动作-状态模型是局部一阶近似；真实系统有摩擦、柔顺、关节限位。
- 仿真不是 G1 数字孪生；只验证「延迟会吃掉增益裕度」这个定性结论。
- 检索 RMSE 仍有 3–5cm；这说明 RAG-Ref 单独不够，必须叠加闭环自适应/视觉伺服。

## 6. 竞赛策略：先锁基线，再把工程投到「执行方差大」的任务

- **W0**：WLA Base + API adapter + 单 LoRA（32 任务混合训练/或先用 Base 零样本）；单任务通道跑通 1 个任务，验证 token/`pivot`/`ee` 绝对位姿。
- **W1**：若评测时段允许，交安全基线，锁「更早提交」tie-break；若不允许，跳过。
- **W2–W3**：RAG-Ref + 相位检测；在 HangCup/PlugInEthernet/StackBowls 上离线回放。
- **W4–W5**：RAG-AS + AC-SysID；仿真 + 单任务 A/B。
- **W6**：全量干跑；固定 H=5；p99/内存/端口隔离。
- **W7**：最终提交；保留 `RAG_ENABLE`/`N_SAMPLES`/`ADAPT_TRIALS` 回滚开关。

任务优先级（先验，单任务通道后更新）：

```text
priority_t = q_t * Δ_t / cost_t
q_t = 失败发生在接触/对齐阶段的比例（先验）
Δ_t = RAG-AC 条件增益（A/B）
cost_t = 参考库/相位/标定/评测成本
```

先做 5 个代表任务：**HangCup（挂）、PlugInEthernet（插）、StackBowls（叠）、ZipUp（拉链）、FoldTowel（变形，防回归）**。前四个是 A 档，FoldTowel 是 B 档对照。每个 5 次 A/B（RAG-AC off/on），同一初始条件；通过标准：≥3/5 +10pp，FoldTowel 不回归 >5pp。

预期收益（保守，不是承诺）：

- 如果 RAG-Ref 把接触任务未来误差从 5cm 降到 3cm，成功率可能 +5–10pp（接触任务）；
- 如果 RAG-AS 再选掉 20% 的坏 chunk，+2–4pp；
- 如果 AC 把跨机器人增益失配吃掉一半，+2–3pp；
- 全局 8–10 个任务生效 → **+2–4pp**；乐观 +5–8pp。320 trials 的 SE≈2.4pp，必须配对 A/B + bootstrap，不能拿 1–2pp 当结论。

# 第 13 轮产物 · RAG-AC 技术报告

> 检索/复核日期：**2026-11-02（UTC）**。对象：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本报告是第 13 轮想法区「RAG-AC」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是补上三者共同缺的**在线自适应层**，并修正第 12 轮关于「在线改 chunk size」的接口错误。

## 0. 结论与边界

### 0.1 一句话结论

官方 WLA 的 30 步 action chunk 是吞吐优势，也是接触精度的结构性弱点；但比「最后 3 厘米」更普遍的问题是**执行层的分布漂移**——评测跨 N 台机器人，相机装配、TCP、桌面高度、光照、物体位置、RTT 都会变，离线标定一次不够。本报告提出 **RAG-AC**：用 33k 成功演示做相位感知的参考轨迹检索（RAG-Ref），用同一 WLA 采样多个候选 chunk 并用检索参考做确定性重打分（RAG-AS），在固定 chunk 的边界做在线系统辨识和自适应增益（AC-SysID）。唯一学习模型仍是 WLA；检索是非参数记忆；自适应控制器只有低维参数；不新增第二个学习策略。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、排行榜 JSON 直接核实 | 规则、API、33,276 eps、WLA `chunk_size=30`、LoRA 支持、榜单 29.7% |
| B | 我们在公开数据/网页上做的分析，可复现 | 榜单 `step~success` 回归、HangCup 检索实验、动作-状态跟踪拟合 |
| C | 设计假设，需 G0–G9 验证 | RAG-AS 收益、AC 在真机稳定、跨 trial 合规 |

### 0.3 本轮不做什么

- 不从零训 VLA/World Model；官方 WLA 已开源 6B 基座 + LoRA。
- 不做完整 sim-to-real 策略训练；仿真只做控制器/辨识的风洞。
- 不做第二个学习策略/残差 RL/世界模型；检索和自适应控制器都不是学习策略。
- 不做 per-task LoRA/多模型混合；只用一个 LoRA + 任务条件。
- 不做 6D 物体位姿网络；用相对位姿 + 相位参考。
- 不做力/触觉闭环；API 没有。
- **不在线改 `action_chunk_size`**；接口固定，只能提交前选。
- 不把预览榜单的任务排名当实测难度；只当先验。
- 不做 30Hz 广域网伺服；反馈发生在 chunk 边界（H=5 时约 6.7Hz）。

## 2. 问题形式化

### 2.1 评分与不确定性

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}.
```

320 trials 下，若 `p≈0.25`，单次标准误：

```math
\mathrm{SE}(S)\approx \sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

人为干扰轴：

```math
\Delta S_{\mathrm{human}} = \frac{2}{10}\,\Delta p_h = 0.2\,\Delta p_h.
```

报告必须给配对差值的 bootstrap 置信区间，而不是只报两个平均值。

### 2.2 固定 chunk 的时间模型

```math
T_{\mathrm{fb}} \approx \frac{H}{f_c} + \tau.
```

`H` 固定；`f_c` 和 `τ` 实测。不能把 `H` 当在线变量。可在线变的是：参考 `μ_ref`、候选选择 `a*`、增益 `K`、恢复状态。

### 2.3 相位参考

定义任务坐标系 `F_task`（由初始受器/桌面标定或头部双目估计）。对演示 `i` 的相位 `φ`、关键帧 `k`：

```math
T^{i}_{\mathrm{task},ee}(k) = T_{\mathrm{base,task}}^{-1} T_{\mathrm{base},ee}^{i}(k).
```

参考段：

```math
\mathcal{R}(\phi,\pi) = \{(T^{i}_{\mathrm{task},ee}(k:k+H), a^{i}(k:k+H), q_i)\}_{i}.
```

在线查询 `z_t` 与参考的距离用马氏距离/归一化欧氏距离；参考分布：

```math
\mu_{\mathrm{ref}} = \sum_i w_i\, y_i,\qquad
\Sigma_{\mathrm{ref}} = \sum_i w_i (y_i-\mu_{\mathrm{ref}})(y_i-\mu_{\mathrm{ref}})^\top + \Sigma_0.
```

### 2.4 可辨识性条件

自适应控制只在以下条件同时满足时启用：

1. 相位检测置信度高（多信号一致）；
2. 最近窗口有足够激励（`u` 方差 > 阈值）；
3. 辨识残差低于阈值（模型没崩）；
4. 检索置信度高（top-1 margin/协方差/inlier 数）；
5. 任务属于刚体接触类（A 档）；
6. 预测误差/跟踪误差在安全范围内。

任一条不满足 → 回退 VLA 开环或保守 PBVS；不硬做。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / fixed chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port PolicyService (CPU)       │
                    │  ├─ task router (32-way)            │
                    │  ├─ phase detector                  │
                    │  ├─ RAG-Ref (demo index)            │
                    │  ├─ RAG-AS (score N candidates)     │
                    │  ├─ AC-SysID (per-axis a,d)         │
                    │  ├─ recovery (edit/contact)         │
                    │  └─ action adapter (54D → 21D)      │
                    └──────────────┬──────────────────────┘
                                   │ async, batched, N samples
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared WLA server (GPU)            │
                    │  UnifoLM-WLA-1.0 + one LoRA         │
                    └─────────────────────────────────────┘
```

- 每个端口一个 `PolicyService` 实例，独立 `reset()`、独立相位/检索/控制器状态。
- 共享 WLA server 用 session ID 区分端口；模型权重只有一份；LoRA 只有一个适配器。
- 检索索引只读、可共享；每端口只维护查询缓存和控制器参数。
- GPU 6B bf16 约 12GB；一张 24GB/40GB GPU 可服务多个端口，具体并发取决于 batch 和序列长度。

### 3.3 `get_action` 伪代码

```python
class RAGACPolicy:
    def get_action(self, obs):
        self._tick(obs)

        task = self.task_router(obs.language)
        phase, phase_conf = self.phase_detector(obs)
        self._update_sysid(obs)                 # per-axis a,d

        # 1) reference retrieval (RAG-Ref)
        ref, ref_conf = self.rag_ref.query(task, phase, obs)

        # 2) candidate sampling + scoring (RAG-AS)
        candidates = self.vla.sample(obs, n=self.n_samples)  # same checkpoint
        if ref_conf > self.theta_ref and self.n_samples > 1:
            a_star = self.rag_as.select(candidates, ref, phase)
        else:
            a_star = candidates[0]

        # 3) adaptive control (AC-SysID)
        if self.adaptive and self.sysid_ok and ref_conf > self.theta_ref:
            a_cmd = self.ac.track(a_star, ref, obs, phase)
        else:
            a_cmd = a_star

        # 4) recovery
        if self.recovery.triggered(obs):
            a_cmd = self.recovery.hold_or_retrieve(obs, task, phase, ref)

        return self.adapter.to_api(a_cmd, obs, self.token)
```

规则：

- 任何异常 → 返回上一组合法 chunk 或安全 hold；绝不返回 NaN/错误形状。
- VLA 推理异步；冷启动同步；plan 过期用旧 plan + 参考/控制器。
- 每个 chunk 只做一次候选选择和控制更新；不在 chunk 内假装有新反馈。

### 3.4 任务路由

数据集没有 language；线上有。32 个任务的语言是固定集合。用**确定性关键词/任务 ID**路由：

```text
if "ethernet" and "plug in" -> PlugInEthernet
elif "ethernet" and ("disconnect" or "unplug") -> DisconnectEthernet
elif "zip" -> ZipUp
...
else -> fallback: 全任务检索 + VLA language embedding (same checkpoint)
```

路由错误是 RAG 的致命错误（「插网线」检索到「拔网线」）。必须用任务 ID/关键词硬约束；语言 embedding 只做 fallback，不做唯一依据。

### 3.5 相位检测

```text
g_t = gripper position (0 close, 4.5 open)
v_t = ||EE linear velocity||
r_t = ||action_ee - next_state_ee||
m_t = mean(abs(I_t - I_{t-1})) in wrist ROI

phase = APPROACH
if g_t < 2.0 and v_t < v_grasp: phase = GRASP
if g_t < 2.0 and v_t >= v_grasp: phase = TRANSPORT
if r_t > r_contact and v_t < v_align: phase = ALIGN
if phase == ALIGN and |v_t| < v_insert: phase = INSERT
if g_t > 3.5 and v_t > v_release: phase = RELEASE
```

阈值用演示统计 + 数字孪生标定；不要用第二个学习分类器。先导实验发现「只看 gripper 开合」只能覆盖 395/719 条 HangCup，必须叠加 `v_t`、`r_t`、`m_t`。

### 3.6 RAG-Ref

```text
def query(task, phase, obs):
    z = descriptor(obs)                       # relative EE, gripper, progress, visual
    cand = index.shard(task, phase).filter(progress_window)
    d = mahalanobis(z, cand.features)
    w = softmax(-d / tau) * cand.quality
    mu = weighted_mean(cand.future_traj, w)
    Sigma = weighted_cov(cand.future_traj, w) + Sigma0
    conf = margin(d) * inlier_ratio / (1 + trace(Sigma))
    return Reference(mu, Sigma, cand.action_segments), conf
```

- 任务/相位过滤优先于外观。
- 相对位姿先验只用于 rerank，不硬筛。
- 低置信度 → 回退 VLA / PBVS；参考不直接下发。

### 3.7 RAG-AS

```text
def select(candidates, ref, phase):
    best = None
    for a in candidates:
        y = compose_to_absolute(a, obs)       # H-step EE trajectory
        j = mahalanobis(y, ref.mu, ref.Sigma)
        j += lambda_s * smoothness(y)
        j += lambda_phi * phase_mismatch(a, phase)
        j += lambda_g * gripper_timing_error(a, ref)
        if best is None or j < best.j:
            best = (j, a)
    return best.a
```

- 没有学习权重；所有项是几何/统计量。
- N=2 默认；N=4 只在延迟允许时用。
- 如果 `min J > θ_J`，回退 top-1 或 hold/replan；不要强行选一个明显差的候选。

### 3.8 AC-SysID

```text
# per axis, at chunk boundary
for d in 0..D_max:
    a_hat = argmin_a sum_k ||dx_k - a*(u_{k-d} - x_k)||^2
    residual[d] = robust_loss(...)
d_hat = argmin residual
a_hat = fit at d_hat
if residual[d_hat] > theta_sysid or excitation < theta_exc:
    disable adaptation; use conservative gains
else:
    Kp = kp0[phase] / clip(a_hat, a_min, a_max)
    Kd = kd0[phase] / clip(a_hat, a_min, a_max)
    clip K; project to safe set
```

- 每轴独立；`a` 是有效闭环增益，包含低层控制器/H 步保持/柔顺。
- 先间接自适应（辨识 + 调度）；MRAC 作为可选升级。
- 延迟补偿用 `d_hat` 做 Smith/卡尔曼预测；`d_hat` 大时降增益。

### 3.9 恢复与跨 trial

恢复：

```text
if ||e|| > eps or edit_score > theta_e:
    hold position
    re-localize target with head stereo
    retrieve recovery segment from demos
    if match: resume with conservative gain
    else: request VLA replan with new image + language
```

跨 trial（可选）：

```text
theta_task <- Proj(theta_task - eta * grad L_selfsup)
L_selfsup = tracking_error + final_visual_mismatch
```

- 只更新低维控制参数，不更新网络权重。
- `reset()` 时结算上一 episode；每个端口/任务独立。
- **合规待确认**：如果官方认为利用前几次 trial 属于「多模型/不公平」，关闭 `ADAPT_TRIALS`。默认关闭。

## 4. 数学推导

### 4.1 候选评分

```math
J(a) = (y(a)-\mu_{\mathrm{ref}})^\top \Sigma_{\mathrm{ref}}^{-1} (y(a)-\mu_{\mathrm{ref}})
     + \lambda_s \|\Delta^2 y(a)\|^2
     + \lambda_\phi \mathbf{1}[\phi(y(a))\neq \phi_t]
     + \lambda_g \|\tau_g(a)-\tau_g^{\mathrm{ref}}\|^2.
```

`y(a)` 是把候选 chunk 的相对动作 compose 成 base 系后的 H 步 EE 轨迹；`Σ_ref` 用参考分布的协方差 + 正则项。评分器无学习参数。

### 4.2 一阶有效模型与辨识

```math
x_{k+1} = x_k + a \odot (u_{k-d} - x_k) + w_k.
```

对每轴 `j`、候选延迟 `d`：

```math
\hat a_j(d) = \frac{\sum_k (u_{j,k-d}-x_{j,k})\,\Delta x_{j,k}}
                   {\sum_k (u_{j,k-d}-x_{j,k})^2 + \epsilon},
```

```math
\hat d_j = \arg\min_d \sum_k \rho\!\left(\Delta x_{j,k} - \hat a_j(d)(u_{j,k-d}-x_{j,k})\right),
```

`ρ` 为 Huber/截断二次，抑制接触瞬态。激励不足或残差大 → 关闭自适应。

### 4.3 自适应增益与稳定域

无延迟时：

```math
e_{k+1} = (1 - \hat a K H) e_k.
```

稳定条件 `0 < \hat a K H < 2`；有延迟 `d` 个 chunk 时，特征方程：

```math
z^{d+1} - z^{d} + \hat a K H = 0.
```

稳定域随 `d` 缩小；用根轨迹/数值表选 `K`。实践：

```math
K_p = k_p^0(\phi)/\hat a,\qquad K_d = k_d^0(\phi)/\hat a,
```

`k^0` 来自离线仿真稳定域表；投影到 `[K_min,K_max]`。接触段法向乘 0.3–0.5，切向保留。

### 4.4 延迟补偿

用 `d_hat` 预测：

```math
\hat x_{k+\hat d} = x_k + \hat d\, \dot x_k + \frac{1}{2}\hat d^2 \ddot x_k,
```

或 Smith predictor。若 `d_hat` 估计不确定度高，降增益而不是加大预测；预测错了会比不预测更差。

### 4.5 跨 trial 更新（可选）

```math
\theta_{t+1} = \mathrm{Proj}_{\Theta}\left(\theta_t - \eta \nabla_\theta L_t(\theta_t)\right),
```

`L_t` 用自监督跟踪误差/最终视觉偏差；`Θ` 是安全集（增益上下界、偏移上下界）。不更新网络权重；默认关闭。

## 5. 先导实验

### 5.1 数据与口径

- 数据：HangCup `data/chunk-000/file-000.parquet`，719 episodes / 130,565 frames；平均 181.6 帧/条（6.05s）。完整 HangCup 有 1,043 episodes（另一个 parquet 未用）。
- 只用右臂；HangCup 右夹爪有明显开合，左夹爪几乎常开。
- 轨迹对齐：EE xyz 按归一化时间重采样到 100 点；检索实验预测未来窗口（重采样 30 点）。
- 这是单任务先导，不是 32 任务结论；所有数字只用于方向判断。

### 5.2 初始位姿分布

| 量 | 均值 | 标准差 | 范围 |
|---|---:|---:|---:|
| x (m) | 0.2506 | 0.0531 | 0.1308–0.3581 |
| y (m) | -0.2856 | 0.0433 | -0.3665–-0.1517 |
| z (m) | 0.0903 | 0.0248 | 0.0609–0.1862 |
| yaw (rad) | 0.2417 | 0.2532 | — |

位置泛化的实际幅度是**十厘米级**；固定轨迹/单点标定不够。

### 5.3 检索：初始状态不够，中程 + 相位才有效

| 检索方式 | 全轨迹 RMSE（100 点） |
|---|---:|
| 所有演示平均轨迹 | 71.4 mm |
| 初始状态 1-NN | 69.9 mm |
| 随机参考 | 101.9 mm |

初始状态 1-NN 只比平均轨迹好 1.5mm，基本等于「没检索」。中程：

| 进度 p | 平均轨迹基线 | 相位+状态 1-NN | 优于基线的 episode 比例 |
|---:|---:|---:|---:|
| 0.3 | 84.3 mm | **41.6 mm** | 76% |
| 0.5 | 77.5 mm | **48.6 mm** | 73% |
| 0.7 | 57.4 mm | **27.9 mm** | 73% |

结论：**RAG 的价值不在「找到同一起点」，而在「找到同一相位/同一状态的未来」**。只做 keyframe 目标图不够：目标图不含「接下来 H 步怎么走」。

### 5.4 top-5 oracle：重打分有 8–16mm 的空间

| 进度 p | top-1 | top-5 最优（oracle） | 差距 |
|---:|---:|---:|---:|
| 0.3 | 41.6 mm | 28.8 mm | 12.9 mm |
| 0.5 | 48.6 mm | 32.2 mm | 16.5 mm |
| 0.7 | 27.9 mm | 19.7 mm | 8.2 mm |

top-5 里经常有比 top-1 好得多的参考；这支持 RAG-AS 的「候选重打分」，而不是只取最近邻。oracle 是上界；真实收益取决于打分器质量，需 G2/G3 验证。

### 5.5 动作-状态跟踪：每轴增益不同

对 `Δx_t = a·(u_{t-d} - x_t)` 做最小二乘，d=0：

| 轴 | 有效增益 a | R² |
|---|---:|---:|
| x | 0.388 | 0.713 |
| y | 0.348 | 0.839 |
| z | 0.115 | 0.209 |
| roll | 0.253 | 0.510 |
| pitch | 0.070 | 0.162 |
| yaw | 0.343 | 0.900 |

动作-状态误差 RMS：z 约 **16.0 mm**、pitch 约 **0.051 rad**；x/y 约 4–7mm。**高度和俯仰是最不听话的轴，也是插入/悬挂最容易失败的轴。** 这直接支持「按轴辨识 + 按轴调度增益」。

### 5.6 延迟/增益仿真

1D 双积分器，dt=1/30，2.5s 最小 jerk 参考；固定增益按 d=0 调（kp=64, kd=16）：

| 延迟 | 固定增益 RMSE | 最优稳定增益 (kp,kd) | 最优 RMSE |
|---:|---:|---:|---:|
| 0 ms | 1.4 mm | (32, 2) | 0.45 mm |
| 100 ms | 118.9 mm | (16, 12) | 3.3 mm |
| 200 ms | 失稳 | (4, 2) | 14.5 mm |
| 300 ms | 失稳 | (4, 2) | 25.0 mm |

在线辨识：对 `(a,d)` 做 0…12 帧网格搜索 + 最小二乘；无噪声时精确恢复；加 10% 加速度噪声后，测试的 `(g,d)=(1.0,6),(1.4,3),(0.6,6),(1.0,0)` 仍全部 top-1 正确（估计值 1.001/1.371/0.600/0.970，延迟全对）。这说明「在线辨识延迟/增益」在原理上可行；真实 G1 的低层控制器远比双积分器复杂，必须用 G3/G4 验证。

### 5.7 先导实验的边界

- 只用了 HangCup 的前 719 条；没有解码视频，没有视觉描述子。
- 动作-状态模型是局部一阶近似；真实系统有摩擦、柔顺、关节限位。
- 仿真不是 G1 数字孪生；只验证「延迟会吃掉增益裕度」这个定性结论。
- 检索 RMSE 仍有 3–5cm；RAG-Ref 单独不够，必须叠加闭环自适应/视觉伺服。

## 7. 竞赛策略与预算

### 7.1 任务优先级（先验，待单任务通道更新）

- **A 档：自适应优先（接触/对齐/插入/挂/叠/拉链/锁/拧）**：HangCup、DisconnectEthernet、ToolboxStorage、PlugCharger、Unlock、ArrangeTestTubes、OpenPillBottle、OrganizeStationery、PackBag、ZipUp、PaperCupStacking、StoreRacket、StackCups、PlugInEthernet、StackBowls、StoreEarphones、PackPhone、OrganizePencilCase、SyringeWaterTransfer。
- **B 档：VLA 优先（语义/分类/变形/长程）**：FruitCollection、PackDoll、FruitSorting、ColorArrangement、PlacePhotoFrame、OrganizeBookshelf、PickOutBatteries、OrganizeTools、FoldTowel、ClearPlates、SpellRobot、ConveyorSorting、RemovePinnedNote。
- **C 档：低投入/观察**：单任务通道里 `p_t` 接近 0 且失败在早期感知/抓取的任务；保留 VLA 基线。

组合规则：

```text
priority_t = q_t * Δ_t / cost_t
```

`q_t`：失败发生在接触/对齐阶段的比例（先验）；`Δ_t`：RAG-AC 条件增益（A/B）；`cost_t`：参考库/相位/标定/评测成本。先做 A 档中 `q_t` 最高、`cost_t` 最低的 3–5 个。

### 7.2 单任务通道协议

1. 选 5 个代表任务：PlugInEthernet（插入）、HangCup（挂）、ZipUp（拉链）、StackBowls（叠）、FoldTowel（变形，防回归）。
2. 每任务 5 次 A/B：RAG-AC off/on；同一初始条件；记录成功、步骤分、耗时、p99、辨识收敛、恢复次数。
3. 通过：≥3/5 任务 +10pp；FoldTowel 不回归 >5pp。
4. 扫 H=3/5/8（通过不同测试时段/提交；不能在线改）；选 p99 与成功率的最佳折中。
5. 最后才跑 32×10 正式评测。

### 7.3 预算

| 方案 | 成本（估算） | 预期收益 | 建议 |
|---|---|---|---|
| WLA Base 直接适配 | 1–2 人周 | 基线；可能 20–30% | 必做；先锁基线 |
| WLA + 单 LoRA（32 任务） | 1–2 GPU 周 + 1 人周 | +1–3pp（未知） | 做；但不要指望它解决执行 |
| RAG-Ref | 2 人周 + CPU | 接触任务 +3–8pp | 主投 |
| RAG-AS | 1–2 人周 + 1 GPU | +1–4pp；延迟风险 | 做 N=2；N=4 备选 |
| AC-SysID | 1–2 人周 + 1 GPU 仿真 | +1–3pp；稳定性风险 | 做间接自适应 |
| 完整世界模型 | 8+ GPU 周 | 不确定；延迟更差 | 不做 |
| 32 任务各训策略 | 规则禁止 | — | 不做 |

**算力**：1×24GB GPU（WLA LoRA/推理）；1×40GB/80GB（多端口/批处理，可选）；16–32 CPU 核（检索/相位/控制/离线回放）；存储 1–2TB（视频缓存；只缓存关键帧/ROI 可 <100GB）。

**人员**：1 人视觉/检索/相位；1 人 WLA 微调/推理/部署；1 人评测/统计/竞赛策略；可兼职。总计 9–11 周。

### 7.4 提交节奏

- **W0**：WLA Base + adapter + 单任务跑通；验证 token/`pivot`/`ee` 绝对位姿。
- **W1**：若评测时段允许，交安全基线，锁「更早提交」tie-break；若不允许，跳过。
- **W2–W3**：RAG-Ref + 相位检测；离线回放。
- **W4–W5**：RAG-AS + AC-SysID；仿真 + 单任务 A/B。
- **W6**：全量干跑；固定 H=5；p99/内存/端口隔离。
- **W7**：最终提交；保留 `RAG_ENABLE`/`N_SAMPLES`/`ADAPT_TRIALS` 回滚开关。

预期收益（保守，不是承诺）：

- RAG-Ref 把接触任务未来误差从 5cm 降到 3cm → 成功率 +5–10pp（接触任务）；
- RAG-AS 选掉 20% 坏 chunk → +2–4pp；
- AC 吃掉一半跨机器人增益失配 → +2–3pp；
- 全局 8–10 个任务生效 → **+2–4pp**；乐观 +5–8pp。
- 320 trials 的 SE≈2.4pp；必须配对 A/B + bootstrap；不要拿 1–2pp 当结论。

## 8. 创新点清单（持续迭代）

### 8.1 RAG-Ref：相位感知的参考轨迹分布

- **动机**：33k 成功演示不只是训练数据，也是执行时的「参考库」。初始状态检索 ≈ 平均轨迹（先导实验），说明必须检索「同相位/同状态的未来」，而不是「同一起点」。
- **与现有方案差异**：第 12 轮 DG-KEYFRAME 检索「目标-夹爪相对位姿 + 目标图」；RA-VLA 检索 in-context 示例做任务适应；本点检索**未来 H 步轨迹分布**，用于跟踪/打分/恢复，不直接输出动作。
- **技术可行性**：数据字段齐全；相位可用确定性规则；索引 <1GB；CPU 可跑。
- **所需资源**：33k 演示（已有）；CPU；无需额外 GPU 训练。
- **落地步骤**：① 相位分割；② 相对坐标统一；③ 质量权重；④ 索引；⑤ 离线 LOO 评测；⑥ 单任务通道。
- **风险**：相位分割错误；参考分布多峰；透明/变形任务不适用；检索库与评测背景不匹配。

### 8.2 RAG-AS：同模型多采样 + 确定性重打分

- **动机**：生成模型可以采样；与其执行第一个 chunk，不如在 N 个候选里选最像成功演示的。top-5 oracle 比 top-1 好 8–16mm，说明重打分有空间。
- **与现有方案差异**：JevVLA 用学习能量模型打分；PaceVLA 用学习路由器；本点用**非参数检索分数**（Mahalanobis + 平滑 + 相位 + 夹爪时序），不新增学习权重。
- **技术可行性**：WLA 可采样；候选轨迹可由相对动作 compose 得到；打分是几何/统计。
- **所需资源**：1 GPU；N=2 推理；离线验证。
- **落地步骤**：① 采样接口；② 候选 compose；③ 打分项权重；④ 延迟测试；⑤ 单任务 A/B。
- **风险**：N 倍推理延迟；打分器与真实成功不一致；候选多样性不足；单模型合规解释。

### 8.3 AC-SysID：chunk 级在线辨识 + 按轴自适应增益

- **动机**：评测跨 N 台机器人；离线标定会过期；数据里每轴有效增益差异大（x 0.39 vs z 0.12），固定增益不对。
- **与现有方案差异**：第 12 轮固定伺服增益 + 数字孪生标定；VLA-Stem 用第二个 RL 策略；本点用**低维在线辨识 + 确定性增益调度**，不更新网络权重。
- **技术可行性**：EE 位姿/动作 30Hz 可得；一阶模型局部有效；网格搜索/RLS 轻量。
- **所需资源**：CPU；离线稳定域表；仿真。
- **落地步骤**：① 数据拟合每轴 a/R²；② 仿真稳定域；③ 在线辨识；④ 投影/死区；⑤ 真机 A/B。
- **风险**：模型失配；接触瞬态污染辨识；延迟估计错误；自适应引发振荡；安全边界。

### 8.4 固定 chunk 合同：把「自适应 horizon」改成「提交级 H + 在线增益」

- **动机**：官方 `action_chunk_size` 固定，不能在线改；第 12 轮的「RTT 高就调 H」是接口错误。
- **与现有方案差异**：PaceVLA 学习多粒度执行；本点不学新路由器，而是在固定 H 下做控制自适应；H 作为提交级超参数扫。
- **技术可行性**：立即可做；只需 README/接口验证。
- **所需资源**：无额外；单任务通道测 `f_c`/RTT。
- **落地步骤**：① 实测 `f_c`/RTT；② 扫 H=3/5/8；③ 固定 H 提交；④ 记录 p99。
- **风险**：H 选错；RTT 分布变化；评测端控制频率未知。

### 8.5 检索触发恢复：把「场景动了」接到控制环

- **动机**：人为干扰占 20%；恢复不需要识别人类，只需要「场景动了，而且不是我的动作解释的」。
- **与现有方案差异**：第 11 轮 GEO-RESIDUAL 做离线/观测层残差；本点把残差接到「停 → 重定位 → 检索恢复段 → 重规划」。
- **技术可行性**：已有动作条件化残差；头双目可重定位；恢复段可检索。
- **所需资源**：CPU；演示库；单任务通道。
- **落地步骤**：① 残差阈值；② 停/重定位；③ 恢复段检索；④ 失败回退；⑤ 仿真扰动。
- **风险**：漏检；误停；恢复段不匹配；安全。

### 8.6 跨 trial 低维参数记忆（可选，合规待确认）

- **动机**：每任务 10 次 trial；同一机器人的增益/偏移在 trial 间稳定，理论上可适应。
- **与现有方案差异**：TTT-RM/StateMem 更新记忆/权重；本点只更新 10–20 维控制参数，不更新网络。
- **技术可行性**：低维；投影安全；可一键关闭。
- **所需资源**：CPU；单任务通道；官方书面确认。
- **落地步骤**：① 规则确认；② 自监督损失；③ 投影；④ 单任务 A/B；⑤ 默认关闭。
- **风险**：被判定为利用评测顺序/不公平；过拟合；trial 顺序未知；多端口状态串扰。

### 8.7 单 LoRA 多任务适配（训练策略，非独立创新）

- **动机**：官方 WLA 6B + LoRA 可在 24GB 上覆盖 32 任务；per-task LoRA 会被视为多模型。
- **差异**：不做 32 个 adapter；一个 LoRA + language/task 条件。
- **可行性**：官方 2026-09-29 支持。
- **资源**：1–2 GPU 周。
- **步骤**：① 数据统一；② 单 LoRA 训练；③ 任务条件；④ 单任务验证。
- **风险**：任务干扰；LoRA 容量不足；语言映射错误。

## 9. 风险与合规

### 9.1 单模型合规的三种模式

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 相位/接触标签只离线生成；线上只有 VLA | 最低 | 保守首选 |
| C2 确定性控制器 | 检索是非参数记忆；自适应是几何/控制律，无学习权重；VLA 是唯一学习模型 | 低；需向官方说明 | 主推 |
| C3 同 checkpoint 特征 | 视觉描述子用 VLA 同一 checkpoint 的 encoder，不加载第二个模型 | 低–中；需说明 | 需要强描述子时用 |

禁止：加载第二个学习策略/残差网络/独立视觉编码器做在线决策；per-task LoRA 混合；用 RL 训 Stem 策略（除非官方明确允许）。

### 9.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定为第二个模型 | C1/C2/C3；提交材料写清楚；检索/控制器无学习权重 |
| 在线自适应振荡 | 真机不稳 | 投影/死区/保守增益/残差门控；失败回退固定增益 |
| 延迟估计错误 | 补偿反向 | 不确定度高就降增益；不强行预测 |
| 检索 mismatch | 错误参考 | 任务/相位硬过滤；top-k 重打分；置信度低回退 |
| 相位分割错误 | 参考错段 | 多信号；F1 门；低置信度只用任务级参考 |
| 透明/反光/变形 | 视觉/深度失败 | 只对刚体任务启用；腕部 2D + 本体兜底 |
| 跨 trial 合规 | 被判不公平 | 默认关闭；书面确认；`ADAPT_TRIALS=0` |
| N 倍推理延迟 | p99 超标 | N=2；异步；降分辨率；回退 N=1 |
| 固定 H 选错 | 反馈太慢/调用太频繁 | 单任务通道实测 f_c/RTT；H=5 默认 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；SE≈2.4pp |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组；相邻帧不跨 split |
| 先导实验过拟合 | 结论外推过度 | 只当方向；32 任务重做；G1/G4 |
| 安全 | 回撤/重抓碰撞 | 限速/限幅/最大重试；编辑检测即停 |

## 10. 与第 10/11/12 轮的关系

**保留**：

- FACT-VLA 的相位化 BC、CAC 柔顺执行、EGP 证据门控；
- GEO-RESIDUAL 的动作条件化残差、米制表面距离、编辑检测；
- CHUNK-SERVO 的固定小 chunk、视觉伺服、演示目标库、单任务通道；
- 官方 WLA 基座、33k 演示、官方 rubric。

**升级**：

- 单张 keyframe → **相位参考轨迹分布**；
- 固定伺服增益 → **chunk 级在线辨识 + 按轴/相位自适应增益**；
- 单次 VLA 输出 → **同模型 N 采样 + 检索参考重打分**；
- 离线数字孪生标定 → **离线先验 + 在线修正**；
- 「自适应 horizon」→ **固定 H + 自适应增益/参考**（接口修正）。

**剪枝**：

- 不在线改 `action_chunk_size`（接口不允许）；
- 不做第二个学习策略/残差 RL/世界模型（单模型 + 算力）；
- 不做 per-task LoRA（会被视为多模型；只用一个 LoRA + 任务条件）；
- 不做 30Hz 广域网伺服（RTT 不允许；chunk 边界自适应）；
- 不做 6D 物体位姿网络（透明/变形不可靠；用相对位姿 + 检索）；
- 不做力/触觉闭环（API 没有）；
- 不把预览榜单的任务排名当难度表（已证伪）；
- 不做 32 个任务各一个策略（规则禁止）。
