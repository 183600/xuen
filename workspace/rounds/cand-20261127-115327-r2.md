### 第 4 轮灵感驱动研究记录

**灵感词**：开源硬件、推理延迟

**直觉与动机**：

v28 的 KT-MPC/KTCG 把安全性建立在「知识证书 + 跨任务迁移 + 自适应权重」上，但隐含了两个未言明的物理与时间假设：

1. **物理载体已知且可信**：证书默认在某个抽象动力学模型上成立，却默认部署平台的传感器、执行器、足端几何与标定都与建模时一致。开源硬件打破了这个假设——同一份控制器会被装到不同 BOM、不同 3D 打印足、不同电机与 IMU 的自组装双足平台上。开放原理图与固件带来可审计性，但也意味着任何人都能替换零件、重刷固件、改动标定；于是「证书在硬件 A 上成立」不等于「在硬件 B 上成立」。证书必须携带硬件上下文，并在部署时重新确认。

2. **证书在控制周期内有效**：50 Hz 意味着 20 ms 预算，MPC 求解、九证验证、知识推理与解释生成都要挤进同一个预算。若证书基于 t0 时刻的状态，却在 t0+L 才被用于放行，状态已经漂移；此时证书可能「逻辑上正确」但「时序上过期」。延迟因此不是单纯性能指标，而是正确性问题：证书是对某一时刻状态的断言，必须带有效期。

**关键洞见**：把证书从「静态命题」升级为「带硬件上下文与时间戳的时态断言」：

Cert = (φ, HD, t0, L, δ, τ_max)

安全性 = 逻辑有效 ∧ 硬件匹配 ∧ 时序未过期。三者共享同一个实时预算，任一缺失都会产生「看似通过、实则失效」的证书。

**形式化目标（增量）**：

1. 定义硬件描述符 HD = (β, h, C, Σ_s, τ_a) 与归一化硬件距离 d_hw，给出硬件等价类 [HD]_ε 与一致性谓词 Conf(HD, att)。
2. 定义硬件证明知识证书 HAKC = (KC, HD, att, ε_hw, μ_hw)，其中 μ_hw 为硬件迁移因子；给出硬件鲁棒半径 ε_hw = δ_hw / L_hw。
3. 定义时态有效性证书 TVC = (t0, L, δ, v_max)，有效期 τ_max = δ / v_max，新鲜度谓词 Fresh(TVC, t) ⇔ (t − t0) ≤ τ_max 且 L ≤ τ_max。
4. 定义任意时间证书调度器 ACS：保证等级 A_0 ≺ A_1 ≺ A_2，成本 c_0 < c_1 < c_2，在预算 B 内选择最高可完成等级，且不得低于最低保证 A_min；无可行等级时 fail-closed。
5. 定义 v29 准入门 PLCG = KTCG ∪ HAKC ∪ TVC ∪ ACS，证明 Exec_v29 ⊆ Exec_v28，并证明时序有效性与硬件鲁棒性两条引理。

**本轮最大风险**：**硬件身份与标定错配（mis-attestation）**——开源硬件的描述符、标定证明与固件哈希可被伪造、误配或因零件替换而过期，使证书在错误的硬件上下文中被判为有效；这比单纯延迟超时更隐蔽，因为系统会「正常」通过所有证书，却把硬件 A 的知识套用到硬件 B 上。

## 2. 关键算法骨架（在 IP-462~466 骨架上扩展）

### IP-467 Hardware Provenance Descriptor & HAKC

```python
@dataclass(frozen=True)
class HardwareProvenanceDescriptor:
    """HD：开源硬件的可审计身份 + 标定上下文"""
    bom_hash: str                    # β
    firmware_hash: str               # h（可复现构建哈希）
    calibration: np.ndarray          # C ∈ R^m
    sensor_noise_sig: np.ndarray     # Σ_s 指纹
    actuator_latency: float          # τ_a
    scale: np.ndarray                # 各标定参数的量纲尺度 s_j
    weights: np.ndarray              # 各参数权重 w_j

    def distance(self, other: "HardwareProvenanceDescriptor") -> float:
        """归一化硬件距离 d_hw（Mahalanobis 风格）"""
        diff = (self.calibration - other.calibration) / np.maximum(self.scale, 1e-9)
        return float(np.sqrt(np.sum(self.weights * diff * diff)))


@dataclass
class HardwareAttestation:
    """att：硬件标定证明，可由启动自检/安全元件/统计指纹生成"""
    descriptor: HardwareProvenanceDescriptor
    nonce: bytes
    signature: bytes
    measured: np.ndarray             # 本次实测标定值
    issued_at: float
    method: str                      # "secure_element" | "startup_chirp" | "statistical_fingerprint"


def verify_attestation(att: HardwareAttestation, expected_bom: str,
                       expected_fw: str, now: float,
                       max_age: float = 5.0, tol: float = 0.05) -> bool:
    """Conf(HD, att)：开源硬件身份 + 标定新鲜度 + 实测一致性"""
    if att.descriptor.bom_hash != expected_bom:
        return False
    if att.descriptor.firmware_hash != expected_fw:
        return False
    if now - att.issued_at > max_age:
        return False
    if not _verify_signature(att.descriptor, att.nonce, att.signature):
        return False
    rel = np.abs(att.measured - att.descriptor.calibration) / np.maximum(
        att.descriptor.scale, 1e-9)
    return bool(np.all(rel <= tol))


@dataclass
class HardwareAttestedKnowledgeCertificate:
    """HAKC：KC + 硬件上下文 + 硬件鲁棒半径"""
    kc: InterpretabilityEnhancedKnowledgeCertificate
    hd: HardwareProvenanceDescriptor
    att: HardwareAttestation
    margin_hw: float                 # δ_hw：KC 在标定硬件上的安全裕度
    sensitivity_hw: float            # L_hw：对硬件参数的 Lipschitz 敏感度
    mu_hw: float = 1.0

    @property
    def eps_hw(self) -> float:
        return self.margin_hw / max(self.sensitivity_hw, 1e-9)

    def evaluate_on(self, deployed: HardwareProvenanceDescriptor,
                    mu_min: float = 0.7) -> bool:
        """在部署硬件上重估：硬件迁移因子与鲁棒半径"""
        d = self.hd.distance(deployed)
        self.mu_hw = max(0.0, 1.0 - d / max(self.eps_hw, 1e-9))
        return (d <= self.eps_hw) and (self.mu_hw >= mu_min)
```

### IP-468 Temporal Validity Certificate (TVC)

```python
@dataclass
class TemporalValidityCertificate:
    """TVC：证书的时态有效性"""
    t0: float          # 状态采样时刻
    latency: float     # 端到端证书延迟 L
    margin: float      # 状态空间安全裕度 δ
    v_max: float       # 状态漂移速度上界

    @property
    def tau_max(self) -> float:
        return self.margin / max(self.v_max, 1e-9)

    def fresh(self, now: float = None) -> bool:
        now = time.time() if now is None else now
        age = now - self.t0
        return (age <= self.tau_max) and (self.latency <= self.tau_max)

    def residual(self, now: float = None) -> float:
        """剩余有效期，用于调度与告警"""
        now = time.time() if now is None else now
        return self.tau_max - max(now - self.t0, self.latency)


@dataclass
class TimedKnowledgeCertificate:
    """将普通证书封装为带裕度与速度界的时态证书"""
    cert: object
    margin: float
    v_max: float

    def to_tvc(self, t0: float, latency: float) -> TemporalValidityCertificate:
        return TemporalValidityCertificate(t0, latency, self.margin, self.v_max)
```

### IP-469 Anytime Certificate Scheduler (ACS)

```python
@dataclass
class AnytimeCertificateScheduler:
    """ACS：预算内选择最高保证等级；无可行等级则 fail-closed"""
    costs: dict = field(default_factory=lambda: {0: 0.5, 1: 3.0, 2: 8.0})
    a_min: int = 1

    def schedule(self, budget: float,
                 available: tuple = (0, 1, 2)) -> int | None:
        for k in sorted(available, reverse=True):
            if k >= self.a_min and self.costs.get(k, math.inf) <= budget:
                return k
        return None

    def describe(self, level: int) -> str:
        return {
            0: "fallback + last-known-safe",
            1: "reduced-horizon MPC + sampled certificates",
            2: "full-horizon MPC + all certificates + explanation",
        }[level]
```

### IP-470 Hardware Transfer Factor (HTF)

```python
def compute_hardware_transfer_factor(hakc: HardwareAttestedKnowledgeCertificate,
                                     deployed: HardwareProvenanceDescriptor,
                                     lambda_hw: float = 2.0) -> float:
    """μ_hw：硬件差异超过鲁棒半径后指数衰减"""
    d = hakc.hd.distance(deployed)
    eps = hakc.eps_hw
    if d <= eps:
        return 1.0
    return float(math.exp(-lambda_hw * (d - eps)))


def combine_transfer_factors(mu_task: float, mu_hw: float,
                             mu_min: float = 0.3) -> float:
    """CTKTP 的任务迁移因子与硬件迁移因子取合取式乘积"""
    mu_total = max(0.0, min(1.0, mu_task * mu_hw))
    return mu_total if mu_total >= mu_min else 0.0
```

### IP-471 Open-Hardware Latency-aware MPC (OHL-MPC)

```python
@dataclass
class OpenHardwareLatencyAwareMPC:
    """OHL-MPC：带 deadline 的 anytime MPC，超时降级但不得低于 A_min"""
    dynamics: Callable
    period: float
    horizon: int = 20
    kc_list: list = field(default_factory=list)
    acs: AnytimeCertificateScheduler = field(default_factory=AnytimeCertificateScheduler)

    def solve(self, x0: Tensor, budget: float, level: int):
        t_start = time.perf_counter()
        if level == 0:
            u = self._safe_stop_or_pd(x0)
            cert = self._minimal_cert(x0)
        elif level == 1:
            u, cert = self._solve_reduced(
                x0, horizon=max(5, self.horizon // 2), n_samples=20)
        else:
            u, cert = self._solve_full(x0, n_samples=100)

        latency = time.perf_counter() - t_start
        if latency > budget:
            return self._degrade(x0, budget, level)
        return u, cert, latency

    def _degrade(self, x0: Tensor, budget: float, level: int):
        for lower in range(level - 1, -1, -1):
            if (lower >= self.acs.a_min
                    and self.acs.costs.get(lower, math.inf) <= budget):
                return self.solve(x0, budget, lower)
        return self._safe_stop_or_pd(x0), self._minimal_cert(x0), 0.0
```

### IP-472 Provenance-Latency Certification Gate (PLCG)

```python
@dataclass
class ProvenanceLatencyCertificationGate:
    """PLCG：KTCG ∪ HAKC ∪ TVC ∪ ACS 十二证一体"""
    ktcg: KnowledgeTransilientCertificationGate
    ohlmpc: OpenHardwareLatencyAwareMPC
    hakc_list: list
    acs: AnytimeCertificateScheduler
    expected_bom: str
    expected_fw: str
    mu_min: float = 0.7
    period: float = 0.02

    def admits(self, plan: 'RobotPlan', sensor: dict) -> bool:
        # 1. 硬件证明：身份、固件、标定新鲜度、实测一致性
        att = sensor.get("attestation")
        if att is None or not verify_attestation(
                att, self.expected_bom, self.expected_fw, time.time()):
            return False
        deployed = att.descriptor

        # 2. 硬件上下文下的知识证书（HAKC + Fil_hw）
        for h in self.hakc_list:
            if not h.evaluate_on(deployed, self.mu_min):
                return False

        # 3. 实时预算 B = T_ctrl − I/O − 估计 − 执行
        budget = (self.period
                  - sensor.get("io_latency", 0.0)
                  - sensor.get("est_latency", 0.0)
                  - sensor.get("act_latency", 0.0))
        level = self.acs.schedule(budget)
        if level is None:
            return False  # fail-closed

        # 4. anytime 求解（可能降级）
        u_cmd, timed_cert, latency = self.ohlmpc.solve(
            plan.init_state, budget, level)

        # 5. 时态有效性（TVC + Fil_time）
        tvc = timed_cert.to_tvc(t0=sensor["t0"], latency=latency)
        if not tvc.fresh(time.time()):
            return False

        # 6. 回退到 v28 的九证准入门（结构/语义/迁移/自适应/知识一致性）
        return self.ktcg.admits(plan, sensor)
```

## 3. 复杂度分析（增量更新）

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 |
|---|---|---|---|
| 硬件证明验证 | O(m + n_sig) | O(m) | m 为标定参数维数（≤32），n_sig 为签名验证开销 |
| HAKC 硬件距离与鲁棒判定 | O(N_hakc · m) | O(N_hakc · m) | N_hakc≤50 |
| TVC 计算与新鲜度检查 | O(N_cert) | O(N_cert) | N_cert≤50 |
| ACS 调度 | O(log 3) ≈ O(1) | O(1) | 保证等级数 K=3 |
| HTF 迁移因子 | O(N_kc · m) | O(N_kc) | 与 CTKTP 同阶 |
| OHL-MPC 求解 | O(N·n_x³)（满级），降级可至 O(N'·n_x³)，N'=N/2 | O(N·n_x) | N=20, n_x=12, n_u=6 |
| PLCG 总体 | O(N·n_x³ + N_hakc·m + N_cert) | O(N·n_x + N_hakc·m) | 关键路径仍为 MPC；证书附加开销 <10% |

**实时性**：满级（A_2）证书链在 N=20、n_x=12、n_u=6 时约 8–18 ms；硬件证明验证 <1 ms；TVC/ACS <0.5 ms；HTF <2 ms。若预算不足，ACS 降至 A_1（半时域 + 20 次采样）约 3–6 ms，或 A_0 安全停/PD 约 0.5 ms。关键设计是**任何降级都显式发生且不得低于 A_min**，绝不静默返回过期证书。

## 4. 正确性论证（增量更新）

### 引理 26（硬件鲁棒半径）

**陈述**：设知识证书的后置条件 Q 在标定硬件参数 p0 上成立，且 Q 的边界对硬件参数是 L_hw-Lipschitz 的，安全裕度为 δ_hw。则对任意部署硬件参数 p，只要 d_hw(p, p0) ≤ ε_hw = δ_hw / L_hw，Q 在 p 上仍成立。

**证明**：由 Lipschitz 性，硬件参数偏移引起的后置条件裕度变化不超过 L_hw·d_hw(p,p0)。当 d_hw ≤ δ_hw/L_hw 时，裕度消耗不超过 δ_hw，故 Q 仍成立。∎

**注**：该引理是**条件性**的——L_hw 与 δ_hw 必须由标定实验估计；若估计偏乐观，则 ε_hw 被高估，正是本轮最大风险的来源。

### 引理 27（时态有效性）

**陈述**：设证书在 t0 时刻基于状态 x(t0) 生成，谓词 Q 在 x(t0) 的 δ-邻域内成立，且系统状态满足 ||ẋ(t)|| ≤ v_max。若证书延迟 L 满足 L ≤ τ_max = δ / v_max，则 Q 在应用时刻 t1 = t0 + L 仍成立。

**证明**：||x(t1) − x(t0)|| ≤ ∫_{t0}^{t1} ||ẋ(t)|| dt ≤ v_max·L ≤ δ。故 x(t1) 落在 x(t0) 的 δ-邻域内，Q 仍成立。∎

### 引理 28（anytime 单调性与 fail-closed）

**陈述**：若保证等级满足 A_2 ⇒ A_1 ⇒ A_0（验证强度递减）且成本 c_0 < c_1 < c_2，则其准入集合满足 Exec(A_2) ⊆ Exec(A_1) ⊆ Exec(A_0)。ACS 在预算 B 下返回的最高等级 k 满足 k ≥ A_min，或返回 None 并触发安全停。

**证明**：等级越高，施加的证书合取项越多，故准入集合随等级单调收缩。ACS 从高到低枚举，仅当 k ≥ a_min 且 c_k ≤ B 时返回；若全部不满足则返回 None，PLCG 随后 fail-closed。∎

### 定理（v29 PLCG 的增强安全性与包含关系）

**陈述**：对任意计划 Π，`PLCG.admits(Π) = True` ⟹ Π 同时满足：
1. 硬件身份与标定一致（Conf）；
2. 所有 HAKC 在部署硬件上处于鲁棒半径内（Fil_hw）；
3. 证书在应用时刻时序未过期（Fil_time）；
4. 保证等级不低于 A_min（Fil_assurance）；
5. v28 的九证全部通过。

并且 Exec_v29 ⊆ Exec_v28。

**证明**：PLCG.admits 依次执行上述五项检查并全部取合取，任一失败即返回 False；最后回退到 KTCG.admits 保证 v28 条件。由于 Exec_v29 = Exec_v28 ∩ Fil_hw ∩ Fil_time ∩ Fil_assurance，与额外集合求交只会收缩，故 Exec_v29 ⊆ Exec_v28。∎

**注**：该定理的安全性依赖于 att 的真实性、ε_hw 的保守性与 v_max/δ 的有效性；任一前提被违反，结论不成立。这正是下一节风险 R25 的形式化表述。

## 5. 实验设计（硬件矩阵 × 延迟注入）

### 5.1 硬件矩阵

| 平台 | 差异来源 | 关键参数 |
|---|---|---|
| H_A | 名义平台 | 标准足长、IMU 噪声基线、执行器延迟 τ_a≈2 ms |
| H_B | 加长足端 + 慢执行器 | 足长 +30%，τ_a≈5 ms，摩擦系数偏高 |
| H_C | 磨损 + 噪声 IMU | 摩擦下降 20%，IMU 噪声 +2 dB，关节零位漂移 |

将 H_A 上生成的 HAKC 直接迁移到 H_B/H_C，分别在「无硬件证明」「有硬件证明但无 HTF」「完整 PLCG」三种配置下测试。

### 5.2 延迟注入

在证书链上注入 0/5/10/15/19 ms 的人工延迟，比较：
- v28（无 TVC）：证书一旦生成即放行；
- v29（有 TVC）：按 τ_max 判定新鲜度，过期即拒绝或降级。

### 5.3 指标与验收阈值

| 指标 | 定义 | 验收目标 |
|---|---|---|
| 不安全放行率 UAR | 放行但实际违反安全约束的比例 | ≤ v28 基线，且在 H_B/H_C 上显著下降 |
| 误拒率 FRR | 安全计划被拒绝的比例 | <5%（A_2），降级后 <8% |
| 过期证书放行数 | age > τ_max 仍被放行的次数 | = 0（由构造保证） |
| 控制回路 p99 延迟 | 端到端单步耗时 | < T_ctrl（20 ms） |
| 降级率 | 落入 A_1/A_0 的比例 | 延迟 10 ms 时 <20% |
| 硬件错配检出率 | H_B/H_C 被正确拒绝或降级的比例 | >95% |

### 5.4 预期结果（设计目标，非实测）

1. TVC 通过构造消除过期证书放行；代价是高延迟下误拒率上升，需 ACS 降级吸收。
2. HAKC + HTF 能在 H_B/H_C 上拒绝大部分由硬件差异导致的误导性知识迁移；但对「标定被伪造且统计指纹一致」的攻击无效（见 R25）。
3. ACS 将 deadline miss 转化为显式降级，p99 延迟可控；A_min 保证不会静默降到纯 PD。

## 6. 已知风险与缓解（增量更新）

| 风险编号 | 描述 | 严重度 | 缓解措施 | 剩余风险 |
|---|---|---|---|---|
| R25 | **硬件身份/标定错配（mis-attestation）** | **高** | 1) 启动 chirp 自检 + 统计噪声指纹；2) 标定证明签名与短有效期；3) 保守 ε_hw 与 fail-closed；4) 定期重标定 | 物理上合理但错误的标定可同时骗过签名与统计检验；开源硬件常缺少安全元件 |
| R26 | 延迟导致频繁误拒/降级 | 中 | 1) anytime 分级；2) 关键证书缓存但受 τ_max 约束；3) 预算预测与预留 | 高动态场景下 τ_max 很小，缓存几乎不可用 |
| R27 | 降级静默降低保证等级 | 中 | 1) A_min 硬约束；2) 降级必须写入审计日志并告警；3) 连续降级触发任务中止 | 操作员可能忽略告警 |
| R28 | 开源硬件缺少可信根，签名不可信 | 高 | 1) 无安全元件时降级为「统计指纹 + 人工确认」；2) 供应链 BOM 审计；3) 可复现构建哈希 | 纯软件证明无法抵抗物理替换 |
| R29 | 时间戳/时钟不同步导致 TVC 误判 | 中 | 1) 使用单调时钟；2) 传感器时间戳与控制器时钟对齐；3) 时钟漂移上界纳入 τ_max | 跨设备时钟漂移难以完全消除 |

## 7. 本轮最大风险（最终确认）

**一句话**：**硬件身份与标定错配（mis-attestation）**——开源硬件的描述符、标定证明与固件哈希可被伪造、误配或因零件替换而过期，使证书在错误的硬件上下文中被判为有效；这比单纯延迟超时更隐蔽，因为系统会「正常」通过所有证书，却把硬件 A 的知识套用到硬件 B 上，且延迟压力会进一步诱使系统跳过重标定与重证明。
