# 第 3 轮迭代（灵感循环 v3：「多模态大模型」×「轻量化结构」）—— 把 VLM 从「运行时裁判」降级为「离线语义编译器」

> **本轮是「换发动机」，不是「换车」。** 承接 v2（UIP-01′~15）的结论：最大得分缺口是 `human_*` 的**反向撤回**，而公开数据零覆盖；恢复闭环需要三件事——**看懂语义、判准步骤、跑得够快**。v2 用 Gazebo 解决了「判准」和「造数据」，但在「看懂」上留了隐患：几何谓词对"盖子被拧回去""拉链被拉开"这类**语义等价、几何近似**的撤回不敏感，而引入外部 VLM 又撞「单模型」合规红线。本轮两个灵感词正好补这两个洞：
>
> - **多模态大模型**：不当在线裁判，而当**离线语义编译器 + 教师**——把语言/计分点/干扰文本编译成可执行子目标程序、谓词与恢复脚本；把语义判断**蒸馏**进轻量头。
> - **轻量化结构**：不是"把模型砍小"，而是**单骨干 + 参数高效头 + token 剪枝 + 早退 + 量化 + 技能宏**，让"编译出来的语义"在推理期只花一份骨干的算力，并服务 N 端口并发。

---

## 0. 承接与诊断（哪些继续、哪些换掉）

| v2 资产 | 本轮处置 | 理由 |
|---|---|---|
| UIP-11 GSO（几何判分神谕） | **保留为"几何半场"** | 对位置/堆叠/插入深度可靠；对语义撤回不可靠 |
| UIP-12 DRF（扰动-恢复数据工厂） | **保留，并升级为编译器验证集** | 造出的 (干扰→撤回→恢复) 三元组，正好给语义程序做**回归测试** |
| UIP-01′ RHPV-D（滚动验证-重做） | **升级为 UIP-16 + UIP-17** | 验证器从"手写规则"变成"编译 + 蒸馏"；`regressed` 判据从几何升级为语义-几何双通道 |
| UIP-13 ACS / UIP-08′ LAT-ENG | **合并进 UIP-18 + UIP-22** | 块长只是轻量计算配置的一个维度，统一到"算力预算"里调度 |
| UIP-14 MSGR（技能图） | **并入 UIP-16（程序图）+ UIP-21（恢复宏）** | 技能图不该手工建；应由语义编译器从计分点生成 |
| UIP-05 LCAG（语言分解） | **升级为 UIP-19 + UIP-20** | 语言可供性用 VLM 离线蒸馏，推理期不调外部大模型 |
| UIP-15 CSG（可信度安全阀） | 保留 | 轻量化后延迟波动更需护栏 |

**最关键的一句诊断**：v2 的验证器是"人写谓词"，覆盖面受限于人；v3 让 **MLLM 写谓词、几何与蒸馏头来验收**——人只做审计，不做瓶颈。

## 1. 两个灵感词的直觉解释

1. **多模态大模型 = 离线"语义编译器"，不是在线"裁判"。**
   直觉：你请一位资深工程师在**赛前**把 32 个任务拆成工序卡（先抓什么、什么算完成、被谁捣乱、怎么补救），而不是比赛时每帧打电话问他。离线调用没有延迟压力，也不会把"外部大模型"带进提交物。
   严谨：把 VLM 视为函数 `Compile: (语言 l, 计分点 s, 干扰文本 h, 少量示范 D) → 程序 P_τ`，并把它的帧级判断作为**教师软标签**，蒸馏到共享骨干上的轻量头。

2. **轻量化结构 = "一份骨干，多种极轻外设"。**
   直觉：像一台主机跑多个容器——权重共享，按任务热插拔很小的适配器；能少算的 token 就少算，能在浅层出结果就不跑深层。
   严谨：推理配置 `c=(r,e,q,ρ)`（视觉 token 保留率、early-exit 层、量化位宽、LoRA 秩），在延迟约束 `L(c)≤B` 下最大化期望得分；最终产物仍是**一个 checkpoint、一条骨干**。

## 2. 严谨定义

**定义 1（任务语义程序）**：对任务 τ，`P_τ=(V,E,{g_v},{φ_v},{μ_v},π_rec)`。`V` 为子目标节点，与 `scoring_points` 一一对齐；`E⊂V×V` 为偏序（"末步分值更大"⇒ 保前置、搏末步）；`g_v` 为自然语言子目标；`φ_v` 为可执行谓词；`μ_v` 为技能宏；`π_rec` 为撤回后的恢复策略。

**定义 2（可执行谓词 DSL）**：
`φ ::= geom(r) | sem(c,r) | φ∧φ | φ∨φ | ◇_[t1,t2] φ | ↑φ | ↓φ`。
`geom` 读仿真/检测器几何量（位置、接触、插入深度）；`sem` 读蒸馏语义头（"盖子已拧上""拉链已闭合""毛巾已展开"）；`◇` 为时间窗内成立；`↑` 为完成、`↓` 为**回退（regressed）**。编译器用 **JSON-Schema 约束解码**，保证输出可解析、可执行、可被 GSO 回放检验。

**定义 3（教师-学生蒸馏）**：教师 `q=VLM(frames,l,g_v)` 给帧级分布（done/ongoing/regressed/fail）+ 可供性热图 + 关系图；学生 `p_θ` 为骨干上的轻量头。损失
`L = E[CE(p,q)] + λ_a L_aff + λ_t L_temporal + λ_c L_consistency`。
**教师只在离线出现，提交物为单一 checkpoint（骨干+头）**，从而把"多模态大模型"转化为"单模型内部能力"。

**定义 4（轻量计算配置与预算）**：`c=(r,e,q,ρ)`；单次 `get_action` 延迟近似
`L(c) ≈ α + β·r + γ·(e/ E_max) + δ/q`，
在 `L(c) ≤ B` 下选 `c` 最大化 `V(c)=P(success|τ,c)`。求解用"阶段分层 + 拉格朗日乘子"：接触密集步提高 `r`、降低 `e`；远距离搬运降低 `r`、提高 `e` 并加大 `k`。

**定义 5（恢复宏库）**：`M={(trigger: ↓φ_v, macro: m, cost: c_m)}`。检测到 `regressed` 后，在满足 UIP-15 延迟预算的前提下选**最小代价可行宏**（如 `unzip→zip`、`close→open→reclose`、`stack→unstack→restack`）。

## 3. 本轮核心命题与瓶颈假设

- **H1（最高杠杆）**：**语义撤回**（拧回、拉开、翻开、拿走）无法靠纯几何稳定判定；"离线 VLM 编译 + 在线蒸馏头"是同时满足**判得准**与**单模型合规**的唯一现实路径。
- **H2**：MLLM 的价值主要在**离线生产**（写谓词、标帧、提可供性），而非在线推理；把它放在在线路径上，延迟与合规两头输。
- **H3**：轻量化不是"精度换速度"的单向折中：**token 剪枝若由可供性头引导**，反而降噪、提反应性；坏处是接触密集步容易剪掉关键指尖区域，需要**阶段化保留率**。
- **H4（可证伪）**：几何谓词与语义谓词的**分歧度**可作为"仿真-真机差 / 语义幻觉"的在线探测器——两者一致才前进，分歧则重观测；这比任何单一置信度都更抗自欺。
- **H5**：恢复宏是**短动作块**，可从 UIP-12 DRF 数据里蒸馏/检索，重做代价远低于重新规划整段。

## 5. 本轮最大风险

**一句话**：把 MLLM 的离线语义标签当作"真值"去蒸馏，会把它的系统性偏差悄悄固化进轻量头，形成比"仿真过拟合"更隐蔽的**语义自欺**——模型在错误的子目标上自信地前进，而几何与真机都未必能及时揭穿它。

## 1. 旗舰深潜 · UIP-16 MSC（Multimodal Semantic Compiler）

- **输入**：任务语言 `l`、`scoring_points`、`generalization.human_*`、少量示范 `D`（公开 32 数据集 + UIP-12 生成的干扰三元组）。
- **输出**：定义 1 的语义程序 `P_τ`，以及三样可直接用的东西：① 每步谓词 `φ_v`（含 `↓` 回退判据）；② 蒸馏用帧级软标签；③ 恢复宏候选 `π_rec`。
- **编译流程**：
  1. **结构化提问**：把 `l / scoring_points / human_*` 填进固定模板（不允许自由发挥，降低幻觉面）。
  2. **约束解码**：按 DSL 的 JSON Schema 输出，语法错误直接重采样。
  3. **回放校验**：在 UIP-11 GSO 上回放公开示范，检查"程序判定的步骤边界"与"计分步"是否对齐；不一致则**定点修复**（只改对应 `φ_v`）。
  4. **对抗校验**：用 UIP-12 的"反向撤回"脚本测试 `↓φ_v` 是否真的触发；漏报/误报都回炉。
  5. **导出**：`P_τ` + 软标签 + 宏库给 17/21。
- **可行性**：高。离线一次跑完 32 任务；不占评测接口；不把外部模型带上线。
- **与 v2 差异**：v2 谓词人写、覆盖有限；MSC 把"写谓词"变成可审计的**编译产物**，人只审 `P_τ` 与校验报告。
- **风险**：MLLM 把"看起来像"当"已完成"（例：把半拧上的盖子判 done）⇒ 必须由 UIP-20 的几何半场否决，并只允许修改单条谓词。

```python
# 伪代码：编译 + 校验闭环
def compile_task(task, vlm, gso, drf, max_repair=4):
    spec = build_spec(task)                      # l, scoring_points, human_*
    P = vlm.generate_json(spec, schema=PROGRAM_SCHEMA)   # 约束解码
    for _ in range(max_repair):
        report = gso.replay_check(P, task.demos)         # 步骤边界是否对齐
        report |= drf.adversarial_check(P, task.human)    # ↓ 是否触发
        if report.ok:
            break
        P = vlm.repair(P, report.failing_nodes)          # 只改失败节点
    return P, gso.soft_labels(P), extract_recovery_macros(P)
```

## 2. 次旗舰 · UIP-17 DVC（Distilled Verifier Core）

- **机制**：教师 `q=VLM` 在**离线**对示范/合成帧打四态软标签（done/ongoing/regressed/fail）+ 可供性热图 + 关系图；学生在**共享骨干**上接极轻头（2 层 MLP 或单层 cross-attn，参数量 <2% 骨干）学 `p_θ`。
- **单模型合规论证**：提交物只有一个 checkpoint；教师不参与推理、不打分、不联网。头是同一模型的一部分，不是"多模型集成"。
- **损失**：`L=E[CE(p,q)] + λ_a L_aff + λ_t L_temporal + λ_c L_consistency`；`L_temporal` 用相邻帧状态差监督 `↓`（回退）事件，直接对准撤回。
- **为什么比手写规则强**：语义撤回的视觉证据往往"几何几乎不变"（盖子的位姿差几度），但语义头能捕捉"开/闭"判别特征；且蒸馏后**延迟从秒级降到毫秒级**。
- **风险**：教师偏差被固化（本轮最大风险）；用 UIP-20 分歧门控 + 少量真机锚点做校正，并保留"教师不确定样本"的重标队列。

```python
def distill_loss(p, q, aff_t, prev_state, state):
    ce   = F.kl_div(p.log(), q, reduction="batchmean")
    la   = F.mse_loss(p.affordance, aff_t)
    lt   = F.binary_cross_entropy(p.regress_prob, (state < prev_state).float())
    lc   = consistency(p, q)          # 师生在"高置信且一致"样本上的一致性
    return ce + 0.5*la + 0.5*lt + 0.1*lc
```

## 3. 轻量化：UIP-18 LEC 与 UIP-22 SBM

### UIP-18 · LEC（Lightweight Elastic Compute）
- **四旋钮**：`r`（视觉 token 保留率，按可供性热度裁剪）、`e`（early-exit 层）、`q`（int8/int4 量化）、`ρ`（技能 LoRA 秩）。外加 `k`（动作块长）——**块长不是独立技巧，而是预算解的一部分**。
- **阶段化策略**：远距离搬运 `r↓, e↑, k↑`（省往返）；接触密集步（插入/合盖/拉链）`r↑, e↓, k↓`（保指尖、快纠错）。
- **求解**：对每阶段估 `L(c)` 与 `V(c)`，在 `L(c)≤B` 下取 argmax；用离线网格搜索+在线查表，避免运行时求解开销。
- **风险**：`k` 与声明不一致会伤可信度 ⇒ 声明全局最大 `K_MAX`，实际每次返回 `≤k` 步（评测端每次都会重新调用）。

### UIP-22 · SBM（Single-Backbone Multi-tenant Serving）
- **机制**：N 端口共享一份量化骨干；**每端口独立 KV/历史/状态**（绝不串味）；动态批处理把不同端口的请求拼批；技能 LoRA 按任务热插拔（秩小，切换开销可忽略）。
- **收益**：显存与吞吐最优，延迟方差可控；直接对应 README §6 的"逐步延迟及其波动"可信度。
- **风险**：批处理会抬尾延迟 ⇒ 设批等待上限 + 小批优先，宁可略降吞吐也不让 p99 爆。

## 4. 语义质量：UIP-19 AMKD 与 UIP-20 SGP

### UIP-19 · AMKD（Affordance Multimodal Knowledge Distillation）
- 教师给"哪里可抓/可插/可拧/可拉"的热图与物体关系图；学生在视觉编码器上加**辅助解码头**（可推理期丢弃）。目标是把 `unseen_object` 轴的泛化从"记住 32 类物体"变成"看懂功能"。
- **风险**：热图教师在大视角/遮挡下噪声大 ⇒ 只在教师与几何检测一致时用作强监督。

### UIP-20 · SGP（Semantic-Geometric Predicate arbitration）
- **双裁判**：`geom`（UIP-11，可靠但语义弱）与 `sem`（UIP-17，语义强但可能幻觉）。三态门控：
  - 两者都 `done` → 前进；
  - 两者都 `↓` → 触发恢复；
  - **分歧** → 不前进、不重做，只**重观测/换视角/降 k**，并计入"不确定性账本"。
- **为什么关键**：分歧度是**免费的 OOD 探测器**；它把"仿真-真机差"和"语义幻觉"转成可观测信号，而不是等榜单打脸。
- **风险**：长期分歧会拖慢 episode ⇒ 设分歧预算，超预算则取几何保守分支。

```python
def gate(geom_state, sem_state, sem_conf, budget):
    if geom_state == sem_state == "done":       return "advance"
    if geom_state == sem_state == "regressed":  return "recover"
    if sem_conf < 0.6 or budget.left <= 0:      return "hold_geom"
    return "reobserve"      # 分歧 → 重观测，不冒进
```

## 5. 恢复执行 · UIP-21 LRS（Lightweight Recovery Skill Library）

- **机制**：从 UIP-12 的"撤回→恢复"三元组里抽取短宏（`unzip`, `reopen`, `unstack`, `requeue`, `reinject`…），每个宏是固定长度的动作块或小策略头；`regressed` 触发后按 `(触发谓词, 代价, 成功率)` 检索最小代价可行宏。
- **为什么轻**：恢复不需要重新规划整段任务，只回放/微调一个短技能；计算与延迟都可预算。
- **与 UIP-15 协同**：最大重做次数、单次宏延迟、总抖动上限三重护栏，防"反复重做"。
- **风险**：宏与真实干扰形态不匹配（仿真教的恢复在真机不成立）⇒ 宏库保留多个变体 + 真机校准槽位。

## 6. 统一主循环伪代码（16+17+18+20+21+15）

```python
class V3_Policy:
    def __init__(self, backbone, prog, dvc, lec, lrs, csg):
        ...
    def reset(self):
        self.g = 0; self.redo = 0; self.buf = []

    def get_action(self, obs):
        if not self.buf:
            c = self.lec.pick(obs, stage=self.g, budget=self.csg.left)   # UIP-18
            geom_s = self.prog.pred(self.g).geom_eval(obs)               # UIP-11
            sem_s, conf = self.dvc(obs, self.prog.node(self.g), c)       # UIP-17
            st = self.gate(geom_s, sem_s, conf, self.csg)                # UIP-20
            if st == "advance":
                self.g += 1; self.redo = 0
            elif st == "recover" and self.csg.allow_redo(self.redo):
                self.redo += 1
                macro = self.lrs.best(self.prog.node(self.g))            # UIP-21
                self.buf = list(macro.actions(obs, c))
            elif st == "reobserve":
                self.csg.spend_uncertainty()
            k = self.lec.chunk(stage=self.g)                             # 块长∈预算解
            if not self.buf:
                self.buf = list(self.backbone.act(obs, self.prog, k, c))[:k]
        return self.buf.pop(0)
```

## 8. 合规、算力与时间线

**合规**
- 单模型：教师离线、提交单 checkpoint、头属于同模型；**须确认手册是否限制"开发期使用外部模型"**（当前手册不可取，标待核实）。
- 接口红线：形状/dtype/token/块长严格按 README §3；量化需保证数值稳定，避免动作统计异常伤可信度。

**算力（粗估）**
- 离线：32 任务编译 + 回放校验 + 蒸馏，单卡数天量级；UIP-12 造数据可并行。
- 在线：一份量化骨干 + <2% 头 + 每端口 KV；N 端口按显存分档压测。

**时间线**
1. 第 1–2 周：UIP-16 编译器跑通 5 个代表任务（T26 插网线、T27 叠碗、T19 拉链、T16 叠毛巾、T12 开锁），建立"编译-回放-对抗"校验报告。
2. 第 3–4 周：UIP-17 蒸馏头 + UIP-20 双裁判；E201/E202/E205。
3. 第 5–6 周：UIP-18/22 轻量化与服务压测；UIP-21 恢复宏；E203/E206/E207。
4. 第 7 周起：真机锚点校准，重点验"语义假 done"与"恢复宏可迁移性"。

## 9. 本轮最大风险 & 押注

**一句话**：语义编译器最大的敌人不是算力，而是"教师看起来很对"——若不用几何半场与真机锚点持续否决，轻量头会把 VLM 的幻觉学得又快又便宜，骗过离线指标却在真机上一次都不触发恢复。

**→ 押注：UIP-16 离线语义编译 × UIP-17 蒸馏验证核 × UIP-20 语义-几何双裁判**——它把"多模态大模型"从合规与延迟的双重包袱，转成**离线可审计、在线可预算**的单一模型能力；恢复宏与轻量服务只是把这份能力兑现成步骤分。
