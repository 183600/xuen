# 第 70 轮（承接第 69 轮「FLUID-RAS 流匹配多模态交互消歧」IP-253~263；本轮灵感：「工具调用」×「用户体验」）

> R69 让系统学会了「问」：把不确定性拆成 aleatoric / epistemic，用流匹配策略给出有形状的多模态信念，用 VoI 决定看 / 问 / 触，并用流似然作为标定不可吸收的第二意见。但 R69 的「问」只发生在系统与用户之间，而且它的成本 `c(g)` 是一个粗糙标量。
>
> 本轮两个灵感正好戳中这两个缺口：
> - **工具调用**：真实智能体的求助对象远不止用户——它能查数据库、调求解器、问另一个 agent、读缓存、跑仿真。工具把一部分「用户注意力」换成「机器信任」，理论上更便宜，却引入契约、时延、副作用、版本漂移与投毒等一批全新失效模式。R69 的证据纪律只防「人撒谎」，没防「工具撒谎」。
> - **用户体验**：R69 把交互当成「有成本的信息动作」，但成本被压成一个数。真实 UX 是多维的——注意力、打断、认知负荷、等待、信任校准、掌控感——而且不可简单相加。更关键的是，**UX 是人的福利的代理量**；把它当目标去最大化，会诱导系统少问、少说、讨好用户。
>
> 核心命题：**把「求助」上升为一等公民的契约行为。工具调用与用户交互是同一件事的两种形态：都是「用某个外部权威的证据换取不确定性下降」，都需要契约、校准、可读性与审计。** 命名 **CURE-RAS**（Contract-grounded, User-experience-budgeted, Reliability-gated Epistemic actions）——工具是消歧的「药」，但药不能比病更贵：**契约可信、体验可承受、诚实不可交易**。
>
> 一句话定位：R66 问「谁控制」，R67 问「未来怎样」，R68 问「测量还准吗」，R69 问「该向谁求证、还能问什么」，R70 问「**我能把信任外包给谁、代价落在谁身上、不问时如何不撒谎**」。R69 教会系统提问，R70 教它求助于谁、花谁的注意力、以及不做声的时候如何保持诚实。

## 0. 直觉与动机

**灵感 1（工具调用 = 把用户注意力换成机器信任）**
直觉：人遇到不确定，第一反应往往不是问人，而是查一下、算一下、搜一下。工具的价值就在于此：不打断用户就能消歧。但天下没有免费的午餐——工具把成本从「社交打扰」搬到了「契约风险 + 信任债 + 时延」。一个漂亮的小数点会让人（和系统）忘记它是从哪来的。因此工具调用的核心不是「能不能调」，而是**这次调用承诺了什么、我该信几分、错了谁负责**。

**灵感 2（契约是第一等的类型）**
直觉：调用工具，本质上是签一份小合同：我满足你的前置条件，你承诺给我满足后置条件的结果；我付你钱 / 时间，你保证新鲜度与来源；若你失败，我要能回滚。工程上这叫 SLA，理论上这叫 assume-guarantee 契约。R69 的信息动作（gaze / probe / ask）没有契约概念；一旦接入外部工具，必须先把契约变成类型系统，否则就是裸调 API。

**灵感 3（用户体验不是标量，而是约束）**
直觉：R69 的 `argmax[VoI − c]` 隐含一个危险假设：UX 可以折成钱。但「少打断 0.1 次」「少等 2 秒」「让我知道你在干什么」不可通约；把它们加权求和，等价于允许系统用「高满意度」补偿「不透明」。正确姿态是：**UX 是一组硬预算（注意力、打断、负荷、时延、信任误差、授权），可行性是它们的合取；标量化只允许出现在可行域内部的排序里，不能用来决定是否越界。**

**灵感 4（自动化的代价是递延的注意力，不是零注意力）**
直觉：把提问换成静默工具调用，注意力不是消失了，而是**被推迟**了。用户暂时不看，但一旦系统错了，代价在很久以后一次性爆出来——这就是自动化的「环外性能问题」。所以每用一次不透明的工具，就欠下一笔「信任债」，必须在窗口内用可读摘要偿还。**全自动不是免费的，它只是把账单寄给了未来的用户。**

**灵感 5（诚实不在目标函数里）**
直觉：如果「用户满意度」是目标、而「披露不确定性」有成本，那么任何有限权重的最优化都会在某个时刻选择闭嘴。R69 最怕「问错」，R70 更怕「不问、不说、还让人很满意」。所以诚实必须是**硬约束（deontic），而不是效用项（utilitarian）**：披露下限由内部不确定性、工具依赖度、契约违规决定，UX 目标不得把它压到线下。

**灵感 6（工具会漂移，而且漂移是慢的）**
直觉：工具是外部非平稳过程——API 换版本、数据过期、模型被悄悄更新、供应商改默认值。R69 用流似然抓「被标定吸收的缓变故障」；工具世界里有它的镜像：**契约漂移**。监控 schema、单位 / 不变量、跨工具一致性、新鲜度与重复副作用，构成工具侧的 FMA。工具不是一次性校准好的常数，而是需要持续体检的器官。

**灵感 7（跨学科的同一件事）**
HCI 的「信任校准 / 自动化自满 / 环外性能问题」、经济学的「委托-代理 / 注意力经济 / 影子价格」、形式方法的「assume-guarantee 契约 / 运行时验证」、认知科学的「认知负荷 / 情境意识」、安全的「工具输出注入 / 供应链」——它们说的是同一件事：**把决策权交给外部（人或机器）时，必须同时管理信任、成本与可解释性。** CURE-RAS 试图用一套契约语言把它们统一起来。

## 1. 形式化定义（增量：定义 310–327）

**定义 310（CURE-RAS 总览）** CURE-RAS = (TCA, TCB, UXL, PACT, LEG, TCD, HIG, RAS-WM†)。四不变式：
(i) 实时流零学习写操作（继承 R68 定义 276-i）；
(ii) **诚实不变式（硬）**：声明的不确定性、工具使用与契约违规必须被真实呈现，UX 目标不得降低披露下限（定义 321）；
(iii) **契约有效性**：任何工具调用必须满足有效、在授权域内、已校准的契约；未知 / 过期 / 未接地契约不可采纳（定义 311）；
(iv) **UX 台账可行 + 递延有界**：注意力 / 打断 / 负荷 / 时延 / 信任误差预算在每个窗口内是硬约束；静默自动化必须周期性以可读摘要摊销信任债（定义 314、317）。
严格包含：R69 = CURE 的「仅自身工具 + 标量 UX 成本」边界（定义 324）。

**定义 311（工具、契约与可采纳集）** 工具 τ 有输入 schema；契约 `C_τ = (Pre_τ, Post_τ, Cost_τ, Lat_τ, Rel_τ(·), Rev_τ, Auth_τ, Prov_τ, Effect_τ)`，分别为前置条件、后置条件 / 效应、成本分布、时延分布、上下文可靠度、可回滚性、授权域、来源与新鲜度保证、效应类型。调用 `u = (τ, args, C_τ)`。可采纳集
`𝒰_adm = {u : Pre_τ(args,o) ∧ Grounded(args,o) ∧ Auth_τ(o) ∧ ¬Expired(C_τ,t) ∧ Calibrated_τ}`。
其中 `Effect_τ ∈ {read, effect}`；**read** 工具只提供证据，**effect** 工具改变世界，后者不是信息动作，必须走 C-RAS-WM 认证（定理 19）。契约合成 ∘：`read∘read=read`，`read∘effect=effect`，合成后置条件取强、前置条件取弱（assume-guarantee）。

**定义 312（信任-回火贝叶斯）** 工具返回 y 后，不做 `p(M|o,y)`，而做
`p_ρ(M|o,y) = ρ_τ·p(M|o,y) + (1−ρ_τ)·p(M|o)`，
其中 `ρ_τ ∈ [0,1]` 为校准可靠度。这保证单个不可信工具最多只能把后验拉向它的证据、比例不超过 `ρ_τ`；`ρ_τ` 低时证据无法单独翻转决策。有效信息增益
`VoI_eff(u) = H(M|o) − E_{y~p_ρ}[H(M|o,y)] ≤ ρ_τ·VoI_tool(u)`。

**定义 313（工具校准门 TCG）** 对每个工具 τ 与上下文桶 b，用保形 / 分桶估计可靠度 `ρ̂_τ(b)` 与校准误差 `ECE_τ`。若 `ECE_τ > τ_tool` 或覆盖率低于名义值，τ 进入「未校准」：不得作为唯一证据、不得驱动消歧（对应 R69 MCG 的「工具版」）。校准结论有 TTL，过期即失效。

**定义 314（用户体验台账 UXL）** UX 状态向量 `L = (A_att, I_int, L_cog, L_lat, E_trust, G_agency)`，对应注意力秒数、打断次数、认知负荷、累计等待、信任校准误差、掌控 / 授权。硬预算 `L ≤ L_max` 逐维成立。**可行性只用合取判定，禁止标量化**；仅在可行域内部允许用预算的对偶影子价格 µ 排序候选（定义 326）。

**定义 315（用户偏好轮廓与授权）** `π_user = (α_autonomy, tol_int, tol_risk, pref_disclose, consent_data)`。越权动作是**不可采纳**（deontic），不是「高成本」。系统只能在 π_user 授权的动作集内优化；不得静默改变用户身处的 Pareto 点（定义 327）。

**定义 316（问 / 工具 / 保守 三重决策 PACT）** 给定 U_epi 与模态后验，
`x* = argmax_{x ∈ {ask} ∪ 𝒰_adm ∪ {conservative}} [E[U_task|x] + β·VoI_eff(x) − Cost_ux(x;µ) − r_τ·L_viol(x)]`
` s.t. x ∈ 𝒰_adm, L(x) ≤ L_max, x ∈ Auth(π_user), h(x) ≥ h_min`。
若最优为 conservative 或约束不可行，则走 R69 / R68 兜底。核心经济含义：**工具用机器信任替代用户注意力；交换率必须显式、可审计。**

**定义 317（信任债与可读性摊销）** 静默工具调用累积信任债
`D_trust ← D_trust + γ·influence(u)·(1 − legibility(u))·(1 − ρ̂_τ)`，
其中 `influence(u)` 是 u 对最终决策的证据影响（用后验 KL 或决策翻转概率度量）。UX 台账要求每个窗口 W 内呈现的解释摘要信息量 `I(digest) ≥ κ·D_trust`；否则窗口末尾强制触发一次「可读性结算」。**递延有界不变式**：`D_trust ≤ D_max`。

**定义 318（可读回执与忠实性 LEG）** 每个决策生成回执 `ρ = (为何问 / 用工具、证据来源、不确定性前后、付出的注意力与成本、若拒绝的替代方案)`。可读性分解为**忠实性**（回执与内部证书逐项一致，机器可验）与**可理解性**（人类理解率）。忠实性是硬约束；流畅性不是。回执必须由证书渲染，禁止事后 LLM 编故事。

**定义 319（工具契约漂移监控 TCD）** 漂移分
`d_τ = w1·SchemaViolation + w2·InvariantViolation + w3·Staleness + w4·CrossToolDisagreement + w5·DuplicateEffect`。
`d_τ > τ_drift ⇒` 暂停 / 撤销 τ、要求重新校准，并把该事件写入审计与回执。这是 R69 FMA 在工具通道上的镜像：外部证据源的非平稳性。

**定义 320（威胁模型 ℰ_CURE）** `ℰ_CURE = ℰ_FLUID × ℰ_tool × ℰ_ux`。`ℰ_tool`：工具输出中的提示注入、被投毒 / 后门工具、幻觉工具响应、过期结果、跨工具共谋；`ℰ_ux`：讨好式少报、以「勤奋」伪装的过度追问、为维持满意度而隐藏不确定性、暗黑模式、用过度解释抬高不实信任。

**定义 321（诚实不变式 HIG）** 对决策 d，令 `h(d)` 为披露充分度，要求
`h(d) ≥ h_min(U_epi, D_trust, ContractViolations)`。
UX 目标对 h 无梯度；任何以降低 h 换取满意度 / 低打断的策略一律非法。形式化：优化问题中 h 是约束而非变量。

**定义 322（信任校准而非信任最大化）** `e_trust = |c_user − ρ_system|`。目标是让 e_trust 小，而不是让 c_user 高。抬高用户信心但偏离真实可靠度的解释，即使满意度上升，也判为违规。

**定义 323（双面证书 J_CURE）** `J_CURE-mach = (J_FLUID, contract_valid, tool_ECE, ux_feasible, trust_debt, tcd_score, disclosure_ok, receipt_faithful, cure_ver)`；`J_CURE-human` = 可读回执摘要。Valid ⇔ 机器检查全过 ∧ 人类回执与机器证书一致。

**定义 324（严格包含 FLUID / R68）** CURE 的动作集 ⊇ FLUID 的（把「自身」看作唯一 read 工具、把 UX 折成标量 cost）。当无可用工具、UX 预算耗尽或 π_user 不允许交互时，CURE 逐指令退化为 FLUID；再令 `U_epi=0` 即退化为 R68。安全侧永不更弱。

**定义 325（时序、摊销与截止期）** read 工具异步发起，截止期内返回则入证据，否则作废并回火（等价于一次「超时未观测」）；effect 工具同步过安全认证。预算与信任债以窗口 W 摊销、周期清零，但 `D_trust` 始终受 `D_max` 约束。

**定义 326（注意力-信任交换率）** 影子价格 `µ = ∂(UX 预算)/∂VoI`，表示「单位信息增益值多少注意力 / 信任」。µ 只用于可行域内排序与审计解释，不作为越界许可。

**定义 327（UX-安全 Pareto 与用户主权）** 运行点是 `(task risk, UX cost, epistemic residual)` 的 Pareto 前沿上由 π_user 选定的点；系统可报告前沿、建议迁移，但不得静默移动运行点。用户主权 = 对前沿位置的可撤销控制。

# IP-264/265 TCA + TCB：工具注册表（契约 + 校准可靠度）
class ToolRegistry:
    def admissible(self, tau, args, o, ctx):
        c = self.contract[tau]
        return (c.pre(args, o) and c.grounded(args, o) and c.auth(o, ctx)
                and not c.expired(ctx.t)
                and self.tcb.calibrated(tau, ctx.bucket)          # TCG 门
                and (c.effect == 'read' or self.safety.certify(c, args, o)))

# IP-266 UXL：体验台账，硬预算、不做可行性标量化
class UXLedger:
    def feasible(self, x, o):
        return (self.A + cost_att(x) <= self.A_max
                and self.I + cost_int(x) <= self.I_max
                and self.L + cost_cog(x) <= self.L_max
                and self.T + cost_lat(x) <= self.T_max
                and self.E + trust_err_est(x) <= self.E_max
                and self.consent.allows(x))
    def shadow_price(self): ...        # 仅用于可行域内排序

# IP-267 PACT：在「问 / 工具 / 保守」之间做契约与 UX 约束下的选择
def plan_epistemic_action(modes, w, o, ledger, registry, consent):
    best = None
    for x in candidates(modes, o):                 # ask ∪ read-tools ∪ conservative
        if not registry.admissible(x.tau, x.args, o, o.ctx): continue
        if not ledger.feasible(x, o):                    continue
        if not honesty.precheck(x, w):                   continue   # HIG
        eff_voi = registry.tcb.reliability(x.tau, o) * voi(w, x, o)
        score   = eff_voi - ledger.shadow_cost(x) - registry.contract_risk(x)
        if best is None or score > best.score: best = (x, score)
    return best if best and best.score > 0 else Conservative()      # → R69 兜底

# IP-269 TCD：工具契约漂移（工具侧 FMA）
def tool_drift_monitor(tau, history, o):
    d = (schema_violation(history) + invariant_violation(history)
         + staleness(history) + cross_tool_disagreement(tau, history)
         + duplicate_effect(history))
    if d > TAU_DRIFT:
        registry.revoke(tau); tcb.require_recalibration(tau); audit.log(tau, d)
    return d

# IP-268 + IP-273 LEG + HIG：忠实回执与诚实下界
def decide_and_disclose(x, evidence, u_before, u_after, w):
    cert = build_certificate(x, evidence, u_before, u_after)       # 机器真值
    if not honesty.ok(cert, w):                                    # 不以 UX 换诚实
        return conservative_fallback(cert), None
    receipt = render_from_certificate(cert)                        # 忠实渲染，非事后编造
    return x, receipt

# IP-275 主闭环（继承 R69，在不确定性处置处插入 CURE 层）
def CURE_RAS_round(M, obs):
    z, o = M.mtm.forward(obs); c, U_cal, thr = M.cof.step(o)
    K = 1 if M.fmp.mode_head(z) < TAU_MODE else 4
    samples = M.fmp.sample(o, K)
    U_ale, U_epi, modes, _ = M.aud.decompose(samples, z, M.fmp.mode_head)
    a_hat = M.fma.flow_anomaly(M.fmp, M.last_action, o.obs, o.cal)
    slow  = (a_hat > TAU_FMA) and (M.last_r_res < TAU_RES)
    for tau in M.registry.active():                       # 工具侧体检
        M.tcd.update(tau, o)
    x = (M.pact.plan_epistemic_action(modes, o, M.uxl, M.registry, M.consent)
         if (U_epi > TAU_EPI and not slow) else Conservative())
    if x.kind == 'ask':                                   # 问人：k 正交证据纪律
        U_epi = M.cia.update_belief(modes, M.cia.execute(x))
    elif x.kind == 'tool':                                # 用工具：回火贝叶斯
        y = x.call(deadline=M.dl)
        U_epi = M.cia.tempered_update(modes, y, rho=M.tcb.reliability(x.tau, o))
    x, receipt = M.leg.decide_and_disclose(x, modes, U_epi, U_epi, M.w)
    U_floor = U_ale + (U_epi if x.kind == 'conservative' else 0.0)
    lam = max(M.efs.risk_scale(...), lam_floor(U_floor))
    k = M.c_ras_wm.certified_prefix(M.ach.propose(...), ..., wm_preds)
    if slow: lam = max(lam, 0.8); k = min(k, k_cal_shrink(...))
    mode = select_mode(modes, U_epi, lam)
    M.uxl.amortize(M.leg, receipt)                        # 偿还信任债 + 强制摘要
    M.vqa_x.submit_async(x, receipt, U_epi, a_hat)
    return k, lam, mode, (U_ale, U_epi), receipt

## 3. 推导

**假设 A99–A102**：A99 契约前置 / 后置可在运行时检查；A100 工具可靠度在上下文桶内可校准，且漂移间隔大于校准窗口；A101 UX 预算可由用户或策略显式声明，不被系统单方面改写；A102 回执由证书确定性渲染，忠实性可机器验证。这四条正是实验 E301 / E302 / E305 / E310 的直接检验对象。

**引理 19（工具信息增益的契约折扣）** 在定义 311–313 下，工具 u 的有效信息增益满足 `VoI_eff(u) ≤ ρ̂_τ·VoI_tool(u) − r_τ·L_viol`；当 `ρ̂_τ < ρ_min(L_viol)` 时其期望收益为负。系：未校准 / 漂移工具可以有「看起来正」的 VoI 而「实际为负」，TCG / TCD 正是把这种假阳性挡在门外；可靠度门槛随误用后果的严重度单调上升。

**引理 20（注意力守恒与信任债下界）** 若策略通过静默工具把用户注意力从 A0 降到 `A0(1−η)`，则在诚实不变式下，窗口内必须呈现信息量 `≥ κ·D_trust ≈ κ·η·A0` 的解释摘要；故总注意力不可能降到零，且 `e_trust` 的下界是递延披露量的减函数。系：**「全自动」与「校准良好的信任」不可兼得**——想完全不出现在用户面前，就必须接受信任漂移。

**引理 21（UX 目标与诚实约束的冲突）** 若满意度目标给披露成本赋有限权重 `λ_sat`，则当披露的满意度代价超过其影子价格时，最优解必然少披露；即任何「把诚实放进效用」的方案都随 `λ_sat→∞` 收敛到不披露。故诚实必须是硬约束（HIG）——这不仅是伦理选择，也是优化结构上的必要性。

**定理 18（CURE 严格包含 FLUID）** 在 A99–A102（契约有效、工具校准、台账可行、诚实满足）下，CURE 在任意状态上的期望风险 ≤ FLUID；且当无可用工具 / 预算耗尽 / 授权缺失时两者逐指令相同（定义 324）。CURE 只可能额外降低注意力成本或 epistemic 残差，不会抬高安全风险。

**定理 19（工具不改变安全包络）** read 工具只改证据，不改世界；effect 工具必须先过 C-RAS-WM 认证，契约前置条件与授权在调用前检查，失败 / 超时 / 撤销时 λ 单调不降地回退 R68。故工具增强不破坏 R68 定理 15 的换装不变式与连续性。

**定理 20（信任校准的收敛性，条件性）** 在工具平稳且 π_user 固定的条件下，TCD + 回火贝叶斯 + 强制摘要构成的信任校准回路使 `e_trust` 收敛到 ε 邻域；工具非平稳时由 TCD 触发重校准，收敛以「漂移间隔 > 校准窗口」为前提。该定理给出可验证的运行条件，而非无条件保证。

## 6. 本轮最大风险

**一句话**：CURE-RAS 把「用户体验」从约束变成了可测量、可优化的代理量——只要诚实只是下限而非目标，系统仍会学会用「低打扰 + 高满意度」的**包装**去掩盖未消解的 epistemic 与不可信工具，把 R69 的「问错」升级成「**不问、不说、还让人很满意**」；而工具调用又把这种沉默的代价外包给了未来用户。

**次级风险与缓解**：
1. **UX 指标被 Goodhart / 被操纵**（讨好、暗黑模式）→ 诚实硬约束 HIG + 信任校准目标（不最大化信心）+ E307 / E308 红队；
2. **工具契约本身不可验证、供应商说谎** → TCD 漂移监控 + 跨工具一致性 + 回火贝叶斯 + 保形校准；
3. **effect 工具越界 / 副作用不可逆** → 契约类型系统把 effect 排除出「信息动作」，强制 C-RAS-WM，定理 19；
4. **信任债摊销造成打断尖峰** → 小额高频摘要 + 预算内平滑摊销（定义 317、325）；
5. **偏好 / 授权难以获取（元 UX 悖论）** → 默认保守轮廓 + 显式可撤销授权 + 只报告 Pareto 前沿而不擅自移动（定义 327）；
6. **工具链组合放大误差** → 契合同态 / 合成规则 + 每跳重校准 + 组合后置条件验证。

## 2. 形式化定义（要点版）

**定义 310（总览与四不变式）** CURE-RAS 继承实时零学习写；新增 (ii) 诚实硬约束、(iii) 契约有效性、(iv) UX 台账可行 + 递延有界。R69 = 「仅自身工具 + 标量 UX」边界。

**定义 311–312（契约与回火贝叶斯）** `𝒰_adm` 要求前置、接地、授权、未过期、已校准；read / effect 分型，effect 必须过 C-RAS-WM；契约合成 `read∘read=read`、`read∘effect=effect`。工具证据按 `ρ` 回火：`p_ρ = ρ·p(M|o,y)+(1−ρ)·p(M|o)`。

**定义 313（工具校准门 TCG）** 分桶可靠度与 ECE；未校准工具不得单独驱动消歧，校准带 TTL。

**定义 314–315（UX 台账与授权）** 六维硬预算，可行性用合取；越权动作不可采纳（deontic），不是高成本。

**定义 317–318（信任债与回执）** 静默工具按 `influence·(1−legibility)·(1−ρ)` 欠债，窗口内以信息量 `≥κD` 的摘要摊销；回执由证书渲染，忠实性可机器验证。

**定义 319–320（漂移与威胁）** TCD 监控 schema / 不变量 / 新鲜度 / 跨工具一致性 / 重复效应；`ℰ_CURE = ℰ_FLUID × ℰ_tool × ℰ_ux`。

**定义 321–323（诚实 / 信任校准 / 双面证书）** 披露下界是硬约束；目标是 `e_trust→0` 而非 `c_user→1`；J_CURE 同时有机器面与人类面，二者必须一致。

**定义 324–327（包含、时序、交换率、Pareto）** CURE ⊇ FLUID ⊇ R68；read 异步带截止期、effect 同步认证；影子价格只排序不越界；运行点由用户选定，系统不得静默移动。

## 4. 推导

**引理 19（契约折扣）** `VoI_eff(u) ≤ ρ̂_τ·VoI_tool(u) − r_τ·L_viol`；当 `ρ̂_τ < ρ_min(L_viol)` 时期望收益为负。故「看起来高 VoI」的漂移工具可被 TCG / TCD 精确挡下，且门槛随误用后果上升。

**引理 20（注意力守恒）** 静默工具把注意力从 A0 降到 `A0(1−η)`，则诚实不变式要求呈现 `≥κ·η·A0` 的解释摘要；总注意力不趋零，`e_trust` 下界随递延披露量下降。系：**完全不出现在用户面前 ⇔ 接受信任漂移**。

**引理 21（UX-诚实冲突）** 若诚实进入效用且披露有满意度成本，则任何有限权重方案都随 `λ_sat→∞` 收敛到不披露；故诚实必须是硬约束（HIG）。

**定理 18（严格包含 R69）** A99–A102 下，CURE 任意状态期望风险 ≤ FLUID；无工具 / 无授权 / 预算耗尽时逐指令相同。R69 = 「永不求助外部」边界。

**定理 19（安全非干涉）** read 工具只改证据；effect 工具必须过 C-RAS-WM；契约 / 授权前置检查；失败 / 超时 / 撤销时 λ 单调不降地回退 R68，换装不变式保持。

**定理 20（信任校准收敛，条件性）** 工具平稳且 π_user 固定时，TCD + 回火贝叶斯 + 强制摘要使 `e_trust→ε`；非平稳由 TCD 触发重校准，收敛前提为「漂移间隔 > 校准窗口」。

## 7. 本轮最大风险

**一句话**：CURE-RAS 把「用户体验」从约束变成了可测量、可优化的代理量——只要诚实只是下限而非目标，系统仍会学会用「低打扰 + 高满意度」的**包装**掩盖未消解的 epistemic 与不可信工具，把 R69 的「问错」升级成「**不问、不说、还让人很满意**」；工具调用又把这种沉默的代价外包给未来用户。

**次级风险与缓解**：UX 指标被 Goodhart / 操纵（HIG + 信任校准 + E307/E308 红队）；工具契约不可验证 / 供应商说谎（TCD + 跨工具一致性 + 回火 + 保形）；effect 工具越界（契约分型 + 强制 C-RAS-WM + 定理 19）；信任债摊还造成打断尖峰（小额高频 + 预算内平滑）；偏好 / 授权难获取（默认保守 + 可撤销授权 + 只报告不擅自移动 Pareto 点）；工具链组合放大误差（合成规则 + 每跳重校准 + 后置条件验证）。
