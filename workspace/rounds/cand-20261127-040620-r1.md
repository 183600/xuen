# 第 1 轮 · 灵感：路径规划 × 技术融合

## 0. 一句话直觉

前几轮把证书当成「执行前的点态过滤器」：一个计划要么通过、要么被拒。
但**路径规划**本质上是时空上的**组合**——一条路径由若干段拼接而成，全局安全
并不等于各段安全的简单合取，还必须处理前缀可行性、沿途时序义务与能量单调性。
**技术融合**则提示：几何、语义、能量、规范、统计、IP 这些异质证书不应并列过滤，
而应被一个**代数**融合成一个可组合的路径级证书。

一句话：**把「证书过滤计划」升级为「证书代数驱动的融合路径规划」**。

## 1. 两个灵感词各自刺中了什么

### 1.1 「路径规划」刺中的断点：点态验证 ≠ 路径验证

v23 的 `HPCEPlus.admits(plan, ...)` 是对**单个计划对象**的一次性判定。
它默认计划已经由某个黑箱规划器产出，证书只负责「事后否决」。这留下三个洞：

1. **前缀洞**：一条路径可能整体满足能量预算，但中途某个前缀已经把电量耗到
   安全储备线以下；点态判定看不到前缀。
2. **时序洞**：义务是有截止期的（「在进入路口后 2s 内让行」「在通过期间持续保持
   净空」）。这些义务沿路径进度展开，不能在终点一次性检查。
3. **组合洞**：局部证书为真，拼接后可能失效——两段各自无碰撞，但拼接点的
   曲率/速度不连续会让机械臂或底盘瞬时越界。

结论：证书需要**可组合性（composability）**，而不只是**可判定性（decidability）**。

### 1.2 「技术融合」刺中的断点：并列过滤 ≠ 融合

v23 的准入门是 `HPC-E ∧ CESC ∧ FSVC ∧ IPAttest` 的连言。连言能保证「全都通过」，
但不能表达：

- 不同证书的**强度**差异（覆盖 0.99 与覆盖 0.999 不应等价）；
- 证书之间的**冲突消解**（节能路径与舒适路径在格中如何取中）；
- 多种规划范式的**互补**（RRT* 擅长高维避障、轨迹优化擅长平滑、学习策略擅长
  非结构化场景，谁在什么条件下胜出？）。

结论：需要一个**证书格 + 融合仲裁**，把「与」升级为「带序的融合」。

## 2. 核心猜想（本轮要立住的三根柱子）

### 猜想 A：证书构成有界格，且存在可靠的组合算子

存在偏序 `⊑`（越「小」越严格/可执行集越小）、交 `⊓`、并 `⊔`、底 `⊥`、顶 `⊤`，
以及组合 `⊕`，使得：

- `c1 ⊕ c2` 表示「先满足 c1 再满足 c2」的联合约束；
- 组合**结合**：`(c1⊕c2)⊕c3 = c1⊕(c2⊕c3)`，从而可增量构建路径证书；
- 组合**单调**：`c ⊑ c' ⇒ c⊕d ⊑ c'⊕d`，从而降级可沿路径传播；
- 组合**可靠**：`Valid(c1⊕c2) ⇒ Exec(c1⊕c2) ⊆ {τ1·τ2 | τ1∈Exec(c1), τ2∈Exec(c2)}`。

若此成立，路径证书就能像半环上的路径代价一样被增量累积——这是把规划与证书
真正缝合的关键。

### 猜想 B：证书可行图是自由空间的可靠抽象

在 PRM/RRT* 的采样图上，只保留「边证书可组合且有效」的边，得到**证书可行图**
`G_C`。若 `G_C` 中从起点到终点存在路径，则存在一条满足全局路径证书的真实轨迹。
这给出「先构图、再搜索」的两阶段解耦，且构图可离线/增量完成。

### 猜想 C：多范式融合可用「证书强度 × 时延 × 能量」的约束仲裁

把 RRT*、轨迹优化、学习策略视为一个规划器组合（portfolio）。每轮各产出候选
路径与证书，仲裁器在时延预算内选出「证书最强且代价可接受」的候选；无可行候选时
降级到安全走廊重规划。融合的收益来自范式互补，风险来自仲裁抖动。

## 3. 与 v23 的接口（保持单调退化链）

- 新增模块编号从 **IP-440** 起，接续 IP-439。
- 新执行集 `Exec_v24 = Exec_v23 ∩ Fil_fpc ∩ Fil_pdtl ∩ Fil_eocp`，
  仍满足 `Exec_v24 ⊆ Exec_v23 ⊆ … ⊆ Exec_v18`。
- 路径证书 `Φ(π)` 的每个分量最终都能回落到 v23 的既有证书（SDC/CAC/ACSC/DCSC/
  CESC/FSVC/IPAM），因此新层是「组合层」，不是「替代层」。
- 降级总督把 v23 的最大风险（云边断联 + 覆盖跌破的共振崩塌）转化为**主动重规划**
  问题：规划器在安全走廊内继续工作，而不是被动拒证停机。

## 4. 我特意保留的张力（不急着消解）

1. **可靠性 vs 保守性**：组合算子若为可靠而过度近似，证书可行图会收缩到死锁；
   若近似不足，则可能出现「证书通过但前缀违规」。这是本轮最需要量化的 trade-off。
2. **结合律 vs 精度**：为了可增量组合，`⊕` 往往要做区间/集合的粗化；粗化越强，
   结合律越容易成立，但精度越低。
3. **融合的独立性假设**：不同段/不同模态的证书可能相关（同一遮挡同时影响语义与
   覆盖）。若按独立处理，融合后的置信度会偏乐观。
4. **时延 vs 完备性**：融合组合在 50Hz 控制环内只能做有限次采样，理论完备性
   让位于 anytime 性质。

## 5. 本轮想验证的最小实验

- **可靠性**：随机 10⁴ 条路径，检查「路径证书有效 ⇒ 逐前缀模拟无违规」，目标 0 违反。
- **保守性**：与 oracle（离线穷举证书可行空间）比较，统计可行路径召回率。
- **融合收益**：单范式 vs 融合组合在非结构化场景的成功率/时延/能量 Pareto 前沿。
- **降级**：注入云边断联 + 覆盖跌破，检查是否在安全走廊内恢复规划且执行集单调。

## 6. 本轮最大风险（一句话）

**证书代数为保可靠而做的粗化，可能把「可组合」变成「可组合但过度保守」——
融合路径规划会在复杂场景中大面积死锁，而一旦为缓解死锁放松粗化，前缀时序/能量
义务就可能被漏检，形成「证书通过、轨迹违规」的可靠性缺口。**

## 2. 证书代数（IP-440）

### 2.1 直觉

把每个证书想成一块「允许轨迹的橡皮泥」：证书越严格，橡皮泥越小。组合两段路径，
就是把两团橡皮泥在拼接点粘起来，只保留能连续拼接的轨迹。只要「粘合」满足结合律、
单调性与可靠性，就能像累加路径长度一样，沿搜索树增量累加路径证书。

### 2.2 形式定义

**定义 1（证书格）**：证书集合 `C` 连同偏序 `⊑` 构成格，若：
- `c ⊑ c' ⟺ Exec(c) ⊆ Exec(c')`；
- `c ⊓ c'` 是 `{c,c'}` 的最大下界，且 `Exec(c ⊓ c') = Exec(c) ∩ Exec(c')`；
- `c ⊔ c'` 是 `{c,c'}` 的最小上界，且 `Exec(c ⊔ c') ⊇ Exec(c) ∪ Exec(c')`；
- `⊥` 满足 `Exec(⊥)=∅`，`⊤` 满足 `Exec(⊤)=Traj`。

**定义 2（组合算子）**：`⊕ : C×C → C` 满足
```
Exec(c₁ ⊕ c₂) ⊆ { τ₁·τ₂ | τ₁∈Exec(c₁), τ₂∈Exec(c₂), glue(τ₁,τ₂) }
```
并要求 `⊕` 对 `⊑` 单调。

**性质 1（结合律）**：`(c₁⊕c₂)⊕c₃ = c₁⊕(c₂⊕c₃)`。
*实现注记*：能量用区间加法（结合）、几何用扫掠体并集（结合）、PDTL 用乘积自动机
（结合到同构）、统计覆盖用覆盖下界的最小值（结合）。四类分量均满足。

**性质 2（单调性）**：`c ⊑ c' ⇒ c⊕d ⊑ c'⊕d` 且 `d⊕c ⊑ d⊕c'`。

**性质 3（可靠性）**：`Valid(c₁⊕c₂) ⇒ Exec(c₁⊕c₂) ≠ ∅`，且其中每条轨迹可分解为
分别满足 `c₁`、`c₂` 的两段。

### 2.3 各分量的具体组合规则

| 分量 | `c` 的表示 | `c₁ ⊕ c₂` | 可靠性依据 |
|---|---|---|---|
| 几何 `c_geo` | 膨胀扫掠体 `S₁ ⊕ ε` | `(S₁∪S₂) ⊕ ε` | 扫掠体并集覆盖拼接轨迹 |
| 语义 `c_sem` | 类别-置信度-误差界集合 | 逐类误差界取 max | conformal 误差界可加性（保守上界） |
| 能量 `c_energy` | 区间 `[e_lo, e_hi]` | `[e_lo¹+e_lo², e_hi¹+e_hi²]` | 区间算术包含真实能耗 |
| 时序 `c_deontic` | 自动机状态 + 截止期向量 | 乘积自动机 `⊗` | 乘积自动机语言 = 语言交 |
| 统计 `c_stat` | 覆盖下界 `1−α̂` | `min(1−α̂₁, 1−α̂₂)` | 覆盖下界取最小保持保守 |
| IP `c_ip` | 专利版本 + 特征集 | 特征集并 + 版本取 max | 权利要求簇并集覆盖实现 |

```python
# ============================================================
# IP-440 Fusion Certificate Algebra (FCA)
# ============================================================
@dataclass(frozen=True)
class Cert:
    geo: SweptVolume            # 膨胀扫掠体
    sem: dict[str, float]       # 类别 -> 误差界
    energy: tuple[float, float] # [e_lo, e_hi]
    deontic: AutomatonState     # PDTL 乘积自动机状态 + 截止期向量
    stat: float                 # 覆盖下界 1-α̂
    ip: PatentStamp             # 专利版本 + 特征集

    def __le__(self, other: "Cert") -> bool:
        """c ⊑ c'：c 允许的轨迹是 c' 的子集（逐分量保守比较）"""
        return (self.geo.subset_of(other.geo)
                and all(self.sem[k] >= other.sem.get(k, 0) for k in self.sem)
                and self.energy[0] >= other.energy[0]
                and self.energy[1] <= other.energy[1]
                and self.stat >= other.stat
                and self.ip.covers(other.ip))

def compose(c1: Cert, c2: Cert) -> Cert:
    """路径组合算子 ⊕：结合、单调、可靠"""
    return Cert(
        geo=c1.geo.union(c2.geo),
        sem={k: max(c1.sem.get(k, 0), c2.sem.get(k, 0))
             for k in c1.sem.keys() | c2.sem.keys()},
        energy=(c1.energy[0] + c2.energy[0], c1.energy[1] + c2.energy[1]),
        deontic=c1.deontic.product(c2.deontic),
        stat=min(c1.stat, c2.stat),
        ip=c1.ip.merge(c2.ip),
    )

def valid(c: Cert, V: VersionTuple) -> bool:
    return (c.geo.well_formed()
            and all(e >= 0 for e in c.sem.values())
            and c.energy[0] <= c.energy[1]
            and c.deontic.accepting()
            and c.stat >= 1 - ALPHA
            and c.ip.covers_version(V))


# ============================================================
# IP-441 Certificate-Aware Roadmap (CAR)
# ============================================================
class CertificateAwareRoadmap:
    def __init__(self, sampler, local_certifier, alpha=0.01):
        self.V: list[State] = []
        self.E: dict[int, list[tuple[int, Cert]]] = defaultdict(list)
        self.labels: dict[int, list[Cert]] = defaultdict(list)  # 非支配前沿
        self.local = local_certifier
        self.alpha = alpha

    def add_node(self, x: State) -> int:
        self.V.append(x)
        self.labels[len(self.V) - 1] = [Cert.top()]  # 空路径证书 = ⊤
        return len(self.V) - 1

    def try_edge(self, u: int, v: int, V: VersionTuple) -> bool:
        """仅当边证书有效且与前缀标签可组合时加入 G_C"""
        c_edge = self.local.certify(self.V[u], self.V[v])  # 局部证书
        if not valid(c_edge, V):
            return False
        added = False
        for c_prefix in self.labels[u]:
            c_new = compose(c_prefix, c_edge)
            if not valid(c_new, V):
                continue
            # 能量前缀不变量：该边末端必须仍高于储备
            if c_new.energy[0] > -RESERVE_MARGIN:
                continue
            if not self._nondominated_insert(v, c_new):
                continue
            self.E[u].append((v, c_edge))
            added = True
        return added

    def _nondominated_insert(self, v: int, c: Cert) -> bool:
        """按 (能量上界, 时延, 风险) 做 Pareto 剪枝，保留证书强度更优者"""
        front = self.labels[v]
        if any(dominates(c_old, c) for c_old in front):
            return False
        self.labels[v] = [c_old for c_old in front if not dominates(c, c_old)] + [c]
        return True

    def plan(self, start: int, goal: int, V: VersionTuple) -> Optional[Path]:
        """在 G_C 上做带证书标签的最短路径（label-setting Dijkstra）"""
        dist = {start: 0.0}
        cert = {start: Cert.top()}
        pq = [(0.0, start)]
        while pq:
            d, u = heapq.heappop(pq)
            if u == goal:
                return reconstruct(u)
            for v, c_edge in self.E[u]:
                c_new = compose(cert[u], c_edge)
                if not valid(c_new, V):
                    continue
                nd = d + edge_cost(c_edge)
                if nd < dist.get(v, inf) and c_new <= cert.get(v, Cert.bottom()):
                    dist[v], cert[v] = nd, c_new
                    heapq.heappush(pq, (nd, v))
        return None

# IP-443 Path Deontic Temporal Logic (PDTL)
# ============================================================
class PDTLMonitor:
    """沿路径进度监控：□_I 持续义务、◇_I 截止期义务、U_I until"""
    def __init__(self, formula: str):
        self.A = compile_to_automaton(formula)  # 有界片段 -> O(1) 状态/义务
        self.state = self.A.q0

    def step(self, seg_cert: Cert) -> bool:
        self.state = self.A.delta(self.state, seg_cert.deontic.observation())
        return not self.A.is_dead(self.state)

    def accepting(self) -> bool:
        return self.A.accepts(self.state)

def check_path_deontic(path: Path, formulas: list[str]) -> bool:
    """乘积自动机：多个义务并发监控，状态数 = ∏|Q_i|"""
    monitors = [PDTLMonitor(f) for f in formulas]
    for seg in path.segments:
        for m in monitors:
            if not m.step(seg.cert):
                return False
    return all(m.accepting() for m in monitors)


# ============================================================
# IP-444 Energy-Optimal Certified Path (EOCP)
# ============================================================
def energy_prefix_ok(path: Path, E0: float, reserve: float) -> bool:
    """前缀能量不变量：∀t, E_res(t) ≥ reserve"""
    remaining = E0
    for seg in path.segments:
        # 用区间下界判断最坏情况，保证可靠
        remaining -= seg.cert.energy[1]
        if remaining < reserve:
            return False
    return True


# ============================================================
# IP-442 Multi-Paradigm Fusion Planner (MPFP)
# ============================================================
class FusionPlanner:
    def __init__(self, portfolio: dict[str, Planner], tau_react=0.020):
        self.portfolio = portfolio
        self.tau_react = tau_react

    def plan(self, start, goal, V, deadline=None) -> Optional[Path]:
        deadline = deadline or (now() + self.tau_react)
        candidates: list[Path] = []
        # anytime：按时延预算轮转各范式，谁先给出可验证路径谁先入池
        for name, planner in self._round_robin():
            if now() >= deadline and candidates:
                break
            p = planner.plan(start, goal, V)
            if p is not None and valid_fpc(p, V):
                candidates.append(p)
        if not candidates:
            return None
        # 约束仲裁：时延硬约束下的效用最大化
        feasible = [p for p in candidates if p.latency <= self.tau_react]
        if not feasible:
            return min(candidates, key=lambda p: p.latency)
        return max(feasible, key=lambda p: utility(p))

    def utility(self, p: Path) -> float:
        return (W1 * strength(p.cert) - W2 * p.latency
                - W3 * p.energy_hi - W4 * p.risk)


# ============================================================
# IP-445 Certificate Degradation Governor (CDG)
# ============================================================
class DegradationGovernor:
    def __init__(self, cesc, fsvc, car: CertificateAwareRoadmap):
        self.cesc, self.fsvc, self.car = cesc, fsvc, car

    def degrade(self, failed_layer: str) -> VersionTuple:
        """任一层失效：回退 V_last_valid 并收缩到安全走廊"""
        V_safe = self.cesc.V_last_valid
        # 收缩：仅保留在旧版本证书下仍有效的边
        corridor = {u: [(v, c) for v, c in es if valid(c, V_safe)]
                    for u, es in self.car.E.items()}
        self.car.E = defaultdict(list, corridor)
        return V_safe

    def replan(self, start, goal, failed_layer) -> Optional[Path]:
        V_safe = self.degrade(failed_layer)
        return self.car.plan(start, goal, V_safe)


# ============================================================
# IP-446 Fusion Path Certificate (FPC) 统一签发
# ============================================================
@dataclass
class FPC:
    geo: Cert; sem: Cert; energy: Cert
    deontic: Cert; stat: Cert; ip: Cert

    def valid(self, V: VersionTuple, path: Path) -> bool:
        comps = [self.geo, self.sem, self.energy, self.deontic, self.stat, self.ip]
        return (all(valid(c, V) for c in comps)
                and energy_prefix_ok(path, E0, R)
                and check_path_deontic(path, ACTIVE_FORMULAS))


# ============================================================
# 端到端：证书代数驱动的融合路径规划
# ============================================================
class CFPPPipeline:
    def __init__(self, cfg):
        self.car = CertificateAwareRoadmap(cfg.sampler, cfg.local_certifier)
        self.fusion = FusionPlanner(cfg.portfolio, cfg.tau_react)
        self.governor = DegradationGovernor(cfg.cesc, cfg.fsvc, self.car)

    def step(self, start, goal, V) -> tuple[Optional[Path], dict]:
        # 1. 尝试融合规划
        path = self.fusion.plan(start, goal, V)
        if path is not None and path.cert.valid(V, path):
            return path, {"mode": "normal", "cert": path.cert}
        # 2. 任一证书层失效 -> 降级重规划
        failed = diagnose_failure(self.car, V)
        path = self.governor.replan(start, goal, failed)
        return path, {"mode": f"degraded:{failed}", "version": V}
```

## 4. 复杂度分析

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 |
|---|---|---|---|
| `compose` | `O(d + |sem| + |Q|²)` | `O(d + |sem| + |Q|)` | `d`=特征维，`|Q|`=自动机状态数 |
| CAR 构图（N 节点） | `O(N·k·|Λ|·compose)` | `O(N·|Λ|)` | `k`=近邻数，`|Λ|`=标签前沿宽度 |
| CAR 查询 | `O((|V|+|E|)·log|V|·|Λ|)` | `O(|V|·|Λ|)` | label-setting Dijkstra |
| PDTL 监控 | `O(|π|·∏|Q_i|)` | `O(∏|Q_i|)` | 有界片段下每义务 O(1) 状态 |
| EOCP 前缀检查 | `O(|π|)` | `O(1)` | 区间加法 |
| MPFP 仲裁 | `O(|Π|·plan + |Π|log|Π|)` | `O(|Π|)` | `|Π|=3` |
| CDG 降级 | `O(|E|·valid)` | `O(|E|)` | 只读旧版本证书 |
| 端到端单步 | `O(|V|log|V|·|Λ| + |π|·|Q|)` | `O(|V|·|Λ|)` | 目标 <20ms（热缓存 + anytime） |

**实时性说明**：CAR 可离线/增量构建，在线查询走热缓存；MPFP 采用 anytime 轮转，
`τ_react` 到点即返回当前最优可验证候选；PDTL 限定在有界片段（截止期 + 有界持续），
使乘积状态数与路径长度解耦。

## 5. 正确性论证

### 引理 1（组合代数的结合与单调）
**陈述**：`⊕` 满足结合律，且对 `⊑` 单调。
**证明**：
1. 四类分量分别满足结合律：能量区间加法、扫掠体并集、自动机乘积、覆盖下界最小值。
2. 分量级结合蕴含整体 `Cert` 结合（笛卡尔积逐分量）。
3. 单调性：若 `Exec(c)⊆Exec(c')`，则对任意 `d`，`Exec(c⊕d)⊆Exec(c'⊕d)`，
   因为组合只保留能与 `d` 拼接的轨迹，子集关系在拼接下保持。
∎

### 引理 2（CAR 可靠性）
**陈述**：若 `G_C` 中存在从 `start` 到 `goal` 的路径，则存在真实轨迹 `τ`
满足 `Valid(FPC(τ))`。
**证明**：
1. 每条边加入时都通过 `valid(c_edge)` 且对某个前缀标签 `c_prefix` 有
   `valid(compose(c_prefix,c_edge))`。
2. 由归纳：路径证书 `Φ(π)` 的每个前缀都在节点标签前沿中保留。
3. 由引理 1 结合律，`Φ(π)` 与括号化无关；由组合可靠性，`Exec(Φ(π))≠∅`。
4. 取 `Exec(Φ(π))` 中任一轨迹，逐分量满足 FPC 定义。
∎

### 引理 3（前缀能量不变量）
**陈述**：若对路径每个前缀段累计的最坏能耗不超过 `E₀−R`，则 `∀t, E_res(t) ≥ R`。
**证明**：真实能耗 `cost(τ) ≤ e_hi`（区间上界可靠），故
`E_res(t) = E₀ − ∫cost ≥ E₀ − Σ e_hi ≥ R`。∎

### 引理 4（PDTL 乘积监控可靠）
**陈述**：若 `check_path_deontic(π, Φ)` 返回真，则 `π` 满足所有 `φ∈Φ`。
**证明**：乘积自动机的接受语言等于各自动机接受语言之交；监控逐步模拟
路径进度，`is_dead` 对应违反持续义务，`accepting` 对应所有截止期义务已满足。∎

### 引理 5（降级单调）
**陈述**：对任意失效层 `κ`，`Exec(D_κ(c)) ⊆ Exec(c)`，且 `Exec_v24` 在降级后不增。
**证明**：`D_κ` 只回退到 `V_last_valid` 并删除边，删除边只能缩小可行轨迹集合；
旧版本证书在 v23 中已通过，故新集合是 v23 执行集的子集。∎

### 定理（FPC 的可靠性与相对完备性）
**陈述**：
(1) **可靠性**：`Valid(FPC(π))` ⇒ `π` 同时满足几何/语义/能量/时序/统计/IP 约束。
(2) **相对完备性**：若采样图的分辨率足以表示某条证书可行轨迹，且该轨迹的所有段
证书可组合，则 MPFP 在 `τ_react` 内以任意时间（anytime）极限找到一条可行路径。

**证明**：
(1) 直接由 `Valid(FPC)` 的六分量连言、引理 3、引理 4 得。
(2) CAR 是证书可行轨迹的可靠抽象（引理 2）；采样分辨率保证抽象不丢失可行连通分量；
MPFP 轮转保证在时延预算内持续产生候选，anytime 极限下候选集覆盖各范式的可达解。
∎

### 推论（单调退化链）
`Exec_v24 ⊆ Exec_v23 ⊆ Exec_v22 ⊆ … ⊆ Exec_v18`。
由 `Exec_v24 = Exec_v23 ∩ {π: Valid(FPC(π))}` 直接得。

## 8. 本轮最大风险（最终确认）

**一句话**：证书代数为保可靠而做的粗化，可能把「可组合」变成「可组合但过度保守」——
融合路径规划会在复杂场景中大面积死锁，而一旦为缓解死锁放松粗化，前缀时序/能量义务
就可能被漏检，形成「证书通过、轨迹违规」的可靠性缺口。
