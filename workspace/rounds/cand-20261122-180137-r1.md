# 第 1 轮（新灵感循环第 1 轮；本轮灵感：「状态隔离」×「比赛策略」）

> **基线**：上一轮产出 MetricVoiceGauge-NCD-HUTDH-v20 + IP-420–424（PCA/CTS/CFC/HPC/CFCtrl）。v17 的 CLP/S2C/HCG/PSV/APS/AMC、v19 的 DCM/OGCC/CCV/DRS/OGC、v20 的感知层全部保留。
> 本轮纪律：**状态是隔离的胶囊、策略是竞赛中的选手、证书是裁判**。本轮只做一件事：**让多个候选策略在互不污染的状态胶囊中并行“比赛”，只允许隔离证书完备、且安全支配的胜者提交到真实机器人**。

## 0. 直觉与动机

**灵感 1（状态隔离 → 把“探索”关进互不串味的胶囊）**
直觉：v20 的联邦感知层有一个隐含假设：所有候选计划、感知贡献与共识投票共享同一份可变状态。于是任何一次试探性推演、任何一条被污染的感知投票，都可能改写别人正在使用的状态，使“某个策略的证书”在无人察觉时失效。传统做法是加锁串行化，代价是活性；或者复制全局状态，代价是内存与同步。核心创新：**状态胶囊隔离 (State Capsule Isolation, SCI)**——把全局状态切成互不相交的胶囊 `S = ⊔ S_i`，每个候选策略只在自己的胶囊里做投机推演（copy-on-write），跨胶囊只允许经过**带证书的端口 (Certified Port)**。关键反直觉点：**隔离不是让系统变慢的锁，而是让“多策略并行竞赛”第一次变得可证安全**——因为输掉的策略连同它的胶囊一起回滚，真实状态永远只被一个经过裁判的胜者提交。

**灵感 2（比赛策略 → 用安全支配代替分数最大化）**
直觉：通常“比赛策略”意味着最大化胜率/收益，甚至允许冒险。放到安全关键的多机器人系统里，这会直接制造碰撞。v20 的 CFC 是“投票”，不是“竞赛”；它没有显式地在多个候选计划之间做选择。核心创新：**策略锦标赛 (Strategy Tournament, STS)**——候选策略 `Π = {π_1..π_k}` 在各自的隔离胶囊里推演，得到证书与分数向量 `(m_safe, p_succ, c_cost)`；锦标赛按**字典序安全优先**比较：先比证书给出的安全裕度下界，再比成功率，最后比代价。关键反直觉点：**比赛的“赢”不是得分最高，而是“在安全偏序下支配所有对手且证书干净”**——不可比时宁可退回 v20 默认计划，也不让高收益的冒险策略夺冠。

**灵感 3（对抗性比赛 → 对手也是选手，不是噪声）**
直觉：真实竞赛/多机器人场景里，其他机器人不是环境噪声，而是有策略的对手；它们会占据通道、抢资源、诱导你的策略做出危险动作。v20 的拜占庭共识只处理“投票异常”，不处理“策略被针对”。核心创新：**对抗策略沙盒 (Adversarial Opponent Sandbox, AOS)**——把对手建模为一组候选策略 `O`，在隔离胶囊中与 `π` 对弈；安全裕度取**最坏对手** `m_robust(π) = min_{o∈O} m_safe(π,o)`。关键反直觉点：**稳健不是把对手当成无穷强的敌人，而是把对手当成“另一个需要被证书约束的选手”**——对手也只能通过已声明的端口影响你，越界的耦合会被边界证书直接判污染。

**三者如何统一**
统一为 **v20 证书体系之上的“隔离竞赛层”**：SCI 提供互不污染的状态容器，IBC 提供跨容器的可证边界，STS 提供安全优先的选择规则，AOS 把对手纳入竞赛，TCC 负责“唯一胜者提交 + 其余回滚”。共享状态 `ζ_iso = (capsules, port_versions, taint_set, tournament_bracket, robust_margin, τ_commit, mode_iso)`。统一接口：**仅当 SCI 非干扰、IBC 边界有效、STS 选出安全支配胜者、AOS 的最坏对手裕度达标、TCC 提交未过期时，才把胜者交给 v20 的 CSC 执行；否则退回 v20 当前安全计划**。

## 1. 研究问题（轮次升级版）

- **Q1（状态隔离的非干扰性）**：如何形式化“胶囊 i 的更新不影响胶囊 j 的证书”？端口需要携带哪些版本/不变式信息，才能既允许必要的跨胶囊协作，又不产生隐蔽耦合？

- **Q2（隔离边界的可证性）**：跨胶囊写入在什么条件下必须被拒绝或降级为“污染”？边界证书如何与 v20 的 HPC/CCV 证书组合，使得“隔离安全”与“碰撞安全”互不掩盖？

- **Q3（安全优先的竞赛规则）**：如何定义策略的安全支配偏序，使锦标赛的胜者一定可证安全，同时避免“不可比即全部拒绝”造成活性塌陷？如何在有限算力下用淘汰赛/逐次减半近似全局最优？

- **Q4（对抗与时效）**：对手策略集合 `O` 如何在线更新？最坏对手裕度与 v20 的 `τ_consensus`、APS 新鲜度如何叠加？锦标赛结果过期或未完成时，如何维持 v20 的安全执行？

## 2. 设计原则（在 P31–P33 基础上新增 P34–P37）

**P34 状态隔离非干扰律（State Isolation Non-interference）**
全局状态划分为胶囊 `S = ⊔_{i=1}^m S_i`。胶囊 `Cap_i = (S_i, cert_i, taint_i, ver_i, readset_i)`。跨胶囊读取必须记录 `(port_id, pinned_version)`；写只能写 `S_i`。若一次更新 `Δ` 满足 `touched(Δ) ∩ readset_j = ∅`，则 `cert_j` 保持不变；否则 `cert_j` 被**保守作废**。任何跨胶囊写入必须携带边界证书 `B_{i→j}`，否则目标胶囊置 `taint_j = true` 并作废证书。**证书不能被“未声明”的耦合悄悄改写**。

**P35 边界证书可组合律（Boundary Certificate Composition）**
边界证书 `B_{i→j} = (schema, invariant, version, signature)` 只声明允许跨界的字段与不变式；`B` 有效当且仅当 schema 匹配、invariant 成立、version 等于 `pinned_version`、签名可验。隔离证书 `IBC_i` 与碰撞证书 `Cert_i^col` 是**合取关系**：`Cert_i = IBC_i ∧ Cert_i^col`。任一失效则整体失效，且失效原因必须记录（可审计）。**隔离证书不能替代碰撞证书，碰撞证书也不能掩盖边界污染**。

**P36 竞赛安全否决律（Competitive Safety Veto）**
候选策略 `π` 可入场当且仅当 `Adm(π) = (cert_π valid) ∧ (taint_π = false) ∧ (m_safe(π) ≥ ε)`。锦标赛的选择是**字典序安全优先**：先最大化 `m_safe`，再最大化 `p_succ`，最后最小化 `c_cost`。任何不满足 `Adm` 的策略直接**否决**，不得以高收益翻盘。若候选集合为空或全部不可比，返回 `⊥` 并回退 v20。**安全是 veto，不是加权项**。

**P37 对抗最坏裕度律（Adversarial Worst-case Margin）**
给定对手策略集合 `O`，策略 `π` 的稳健安全裕度定义为 `m_robust(π) = min_{o∈O} m_safe(π, o)`；锦标赛使用 `m_robust` 而非名义 `m_safe`。对手只能通过已声明端口影响 `π` 的胶囊；越界耦合视为污染并否决。对手集合未知时，用保守对手 `o_⊥`（占满所有可用通道、最大化冲突）兜底。**稳健性是对手集合上的最小值，不是平均值**。

## 3. 与基线的接口（如何退化）

- SCI 失效（胶囊机制不可用）⇒ 所有策略串行、共享全局状态 ⇒ 等价 v20 单策略评估（更保守、活性降低）；
- IBC 失效（端口不可验签）⇒ 所有跨胶囊写入视为污染 ⇒ 只允许本地闭环策略 ⇒ 等价 v20 局部安全；
- STS 失效（锦标赛不可用）⇒ 直接采用 v20 当前安全计划 ⇒ 等价 v20；
- AOS 失效（对手集合为空）⇒ `m_robust = m_safe`，退化为单智能体安全 ⇒ 等价 v20（仍安全，但可能被对手针对）；
- TCC 失效（提交超时/未完成）⇒ 不提交任何投机胶囊，回退 v20；
- 五者全失效 ⇒ 完全回退 v20；
- **安全继承**：隔离只能作废/回滚，竞赛只能在可入场策略里选择，提交只能提交一个通过裁判的胜者，故 `Exec_v21 ⊆ Exec_v20`（引理 162）。

## 4. 预期贡献

1. **状态胶囊隔离**：首次把“多策略投机推演”改写为互不污染的隔离胶囊，给出非干扰条件、读集版本固定与污染传播规则；
2. **隔离边界证书**：给出跨胶囊端口的 schema/invariant/version/签名四元组证书，使“隔离安全”与“碰撞安全”可组合、可审计；
3. **安全优先锦标赛**：把“比赛策略”从收益最大化改写为安全支配下的字典序选择，证明胜者一定可证安全，并给出淘汰赛/逐次减半的算力近似；
4. **对抗策略沙盒**：把对手建模为受同一套证书约束的选手，用最坏对手裕度替代名义裕度，避免“被针对的证书”；
5. **唯一提交 + 回滚**：以 copy-on-write 胶囊实现“探索并行、提交唯一”，使 `Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19`，兼顾活性与可证安全。

## 5. 本轮最大风险

**一句话**：如果隔离边界存在**未声明的隐蔽耦合**（例如两个“独立”胶囊共享同一感知时钟、同一随机数种子或同一缓存对象），那么被污染胶囊的坏状态会通过这条隐蔽通道**悄悄改写**另一个胶囊的证书，锦标赛会把一个“看起来干净、实际已被污染”的策略选为胜者——即“隔离幻觉下的带毒夺冠”。

```python
# IP-425 State Capsule Isolation
@dataclass
class Capsule:
    sid: str
    state: Any                 # 该胶囊独占的可变状态（copy-on-write）
    cert: Optional[Certificate]
    taint: bool
    ver: int
    readset: dict              # port_id -> pinned_version


class StateCapsuleIsolation:
    def __init__(self, base_state):
        self.base = base_state
        self.capsules = {}
        self.port_versions = {}    # port_id -> version

    def fork(self, sid):
        # COW：fork 时只建引用，写入时才复制被触碰的页/对象
        cap = Capsule(sid, self.base.cow_clone(), None, False, 0, {})
        self.capsules[sid] = cap
        return cap

    def read_port(self, sid, port_id):
        cap = self.capsules[sid]
        ver = self.port_versions.get(port_id, 0)
        cap.readset[port_id] = ver          # 固定读取版本
        return self.base.read_port(port_id), ver

    def write_local(self, sid, delta):
        cap = self.capsules[sid]
        cap.state.apply(delta)              # 只写 S_sid，绝不触碰其他胶囊
        cap.ver += 1
        cap.cert = None                     # 写后证书必须重验
        return True

    def write_cross(self, sid, target, delta, boundary_cert):
        # 跨胶囊写：必须带有效 IBC，且目标读集版本匹配
        if not boundary_cert.verify(self.port_versions):
            self.capsules[target].taint = True
            self.capsules[target].cert = None
            return False, "BOUNDARY_INVALID"
        self.capsules[target].state.apply(delta)
        self.capsules[target].ver += 1
        self.capsules[target].cert = None
        self.port_versions[boundary_cert.port_id] += 1
        return True, "OK"

    def invalidate_on_commit(self, changed_ports):
        # 非干扰：只有真正读过被改端口的胶囊才需要作废
        for cap in self.capsules.values():
            if set(cap.readset) & set(changed_ports):
                cap.cert = None

    def commit(self, sid):
        cap = self.capsules[sid]
        if cap.taint or cap.cert is None or not cap.cert.valid():
            return False, "UNSAFE_CAPSULE"
        changed = cap.writeset_ports()       # 本次提交触碰的端口
        self.base = cap.state                # 原子替换
        self.invalidate_on_commit(changed)   # 其余胶囊按读集保守作废
        return True, "COMMITTED"

    def rollback(self, sid):
        # 投机胶囊直接丢弃；base 从未被其写入
        self.capsules.pop(sid, None)

# IP-427 Strategy Tournament Selector
class StrategyTournamentSelector:
    def __init__(self, epsilon=0.0):
        self.epsilon = epsilon

    def admissible(self, pi):
        return (pi.cert is not None and pi.cert.valid()
                and not pi.tainted
                and pi.m_safe >= self.epsilon)

    def key(self, pi):
        # 字典序安全优先：安全裕度↑，成功率↑，代价↓
        return (pi.m_safe, pi.p_succ, -pi.c_cost)

    def match(self, a, b):
        if not self.admissible(a) and not self.admissible(b):
            return None, "BOTH_DISQUALIFIED"
        if not self.admissible(a):
            return b, "A_DISQUALIFIED"
        if not self.admissible(b):
            return a, "B_DISQUALIFIED"
        ka, kb = self.key(a), self.key(b)
        if ka > kb:
            return a, "SAFETY_DOMINANCE"
        if kb > ka:
            return b, "SAFETY_DOMINANCE"
        return None, "INCOMPARABLE"          # 触发 v20 回退

    def select(self, strategies, bracket="successive_halving"):
        pool = [p for p in strategies if self.admissible(p)]
        if not pool:
            return None, "NO_ADMISSIBLE"     # 回退 v20
        # 逐次减半：每轮按安全优先键保留前一半，降低评估次数
        while len(pool) > 1:
            pool.sort(key=self.key, reverse=True)
            pool = pool[:max(1, len(pool) // 2)]
        return pool[0], "WINNER"


# IP-428 Adversarial Opponent Sandbox
class AdversarialOpponentSandbox:
    def __init__(self, sci, ccv, opponents, fallback_opponent):
        self.sci = sci
        self.ccv = ccv
        self.opponents = opponents
        self.fallback_opponent = fallback_opponent
        self.undeclared_ports = set()

    def robust_margin(self, pi):
        worst = float("inf")
        for o in self.opponents:
            sid = f"adv::{pi.id}::{o.id}"
            cap = self.sci.fork(sid)
            cap.state.apply(pi.action)
            cap.state.apply(o.action)
            worst = min(worst, self.ccv.min_clearance(cap.state))
            self.sci.rollback(sid)          # 对抗推演不污染真实状态
        if not self.opponents:
            worst = min(worst, self._margin_against(self.fallback_opponent, pi))
        return worst

    def _margin_against(self, o, pi):
        sid = f"adv::{pi.id}::{o.id}"
        cap = self.sci.fork(sid)
        cap.state.apply(pi.action)
        cap.state.apply(o.action)
        m = self.ccv.min_clearance(cap.state)
        self.sci.rollback(sid)
        return m

    def detect_hidden_coupling(self, pi, o):
        # 未声明端口上的读写相交 = 隐蔽耦合 = 污染
        return bool((pi.writeset | o.writeset) & self.undeclared_ports)


# IP-429 Tournament Commit Controller
class TournamentCommitController:
    def __init__(self, sci, aps, ttl_commit=0.5):
        self.sci = sci
        self.aps = aps
        self.ttl_commit = ttl_commit

    def commit(self, winner, tournament_ts, now):
        if winner is None:
            return False, "NO_WINNER"
        if now - tournament_ts > self.ttl_commit:
            return False, "TOURNAMENT_EXPIRED"   # 回退 v20
        if not winner.admissible():
            return False, "UNSAFE_WINNER"
        ok, why = self.sci.commit(winner.sid)    # 唯一胜者原子提交
        if not ok:
            return False, why
        self.aps.update_plan(winner.plan, margin_col=winner.cert.margin)
        return True, "COMMITTED"

    def rollback_all_but(self, winner_sid):
        for sid in list(self.sci.capsules):
            if sid != winner_sid:
                self.sci.rollback(sid)           # 其余投机胶囊全部回滚
```

## 3. 推导

**引理 157（状态隔离非干扰性）** 设 `cert_j` 只依赖 `view_j = (S_j, {(port_p, v_p)}_{p∈readset_j})`。若一次更新 `Δ` 满足 `touched(Δ) ∩ readset_j = ∅`，则 `view_j` 不变，故 `cert_j` 不变；若 `touched(Δ) ∩ readset_j ≠ ∅`，则按 P34 保守作废 `cert_j`。因此任何跨胶囊更新要么不影响 `cert_j`，要么使 `cert_j` 失效，绝不会“在 `cert_j` 不知情时改写它”。∎

**引理 158（边界证书可靠性）** 跨胶囊写若 `B` 无效，目标胶囊被置 `taint` 并作废证书（P34/P35）；`taint` 沿端口图传播，且 TCC 只提交 `taint = false` 的胶囊（P36）。故被污染的胶囊不可能被提交。∎

**引理 159（锦标赛安全性）** STS 的可入场集合 `Adm` 要求证书有效、无污染、`m_safe ≥ ε`；选择键 `(m_safe, p_succ, -c_cost)` 是安全优先字典序。故胜者 `π* ∈ Adm`，即 `cert_{π*}` 有效且 `m_safe(π*) ≥ ε`。因此 `π*` 的动作在 v20 证书语义下零碰撞，`Exec_v21 ⊆ Exec_v20`。∎

**引理 160（对抗稳健性）** 若 `O` 覆盖所有可能对手，`m_robust(π) = min_{o∈O} m_safe(π,o)`，则 `π*` 对每个 `o∈O` 都满足安全裕度下界。若 `O` 只是真实对手集合的下近似，则存在 `o* ∉ O` 使 `m_safe(π*,o*) < ε`，引理不成立——这正是 P37 的边界。∎

**引理 161（提交原子性）** TCC 在一次锦标赛中只对胜者胶囊调用一次 `commit`；提交是 `base = cap.state` 的原子替换，其余胶囊 `rollback`。投机胶囊的写入从未进入 `base`，故探索不会污染真实状态。∎

**引理 162（v21 整体安全继承）** 在同一基线快照与同一候选集合下，SCI 只作废/回滚、IBC 只拒绝越界写、STS 只在 `Adm` 中选胜者、AOS 用最坏裕度收紧、TCC 只提交唯一胜者；五者叠加只能产生 v20 可执行集合的子集，故 `Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19 ⊆ Exec_v18`。∎

## 7. 已知风险与失效模式

1. **隔离幻觉（隐蔽耦合）**：两个“独立”胶囊可能共享同一感知时钟、随机数种子或缓存对象，污染绕过端口与证书，产生“带毒夺冠”。缓解：端口白名单、共享对象静态扫描、随机化隔离测试、COW 深拷贝校验。

2. **安全偏序导致活性塌陷**：若 `m_safe` 普遍接近 `ε`，锦标赛频繁不可比并回退 v20，隔离竞赛退化为串行。缓解：分层 `ε`、允许“同等安全下比成功率”、候选池多样化。

3. **对手集合不完备**：`O` 只是真实对手的下近似，最坏裕度被低估，稳健性失效（引理 160 的边界）。缓解：在线对手发现、保守兜底对手 `o_⊥`、对手模型不确定性罚项。

4. **COW 实现漏洞**：浅拷贝共享可变子对象，写入一个胶囊时另一个胶囊被“隔空”修改，非干扰性被破坏。缓解：写时深拷贝、不可变数据结构、别名检测、属性测试。

5. **版本固定导致过度作废**：高并发端口更新使大量胶囊证书被保守作废，活性下降。缓解：读集合并、版本区间、只作废真正相关的端口。

6. **锦标赛算力/延迟**：候选策略与对手数量增大时，沙盒推演与最坏裕度计算超出控制周期。缓解：逐次减半、早停、并行沙盒、缓存稳健裕度。

7. **污染传播过宽**：一次污染沿端口图否决大量胶囊，造成“一人污染、全员停摆”。缓解：最小割隔离、污染域分区、按端口细粒度传播。

8. **证书组合错误**：`IBC ∧ Cert^col` 的时效不一致（一个过期、一个仍有效）可能被误判为整体有效。缓解：统一证书时间戳与 TTL、合取前先做时效校验。

9. **提交窗口与 APS 不同步**：锦标赛结果在 `TTL_commit` 内但 APS 已换代，提交的计划可能基于过期感知。缓解：`τ_commit` 与 `τ_consensus` 联合校验、提交前二次新鲜度检查。

## 8. 本轮最大风险

**一句话**：如果隔离边界存在**未声明的隐蔽耦合**（共享时钟、随机种子或缓存对象），被污染胶囊的坏状态会绕过端口证书**悄悄改写**另一个胶囊的证书，使锦标赛把一个“看似干净、实则带毒”的策略选为胜者——即“隔离幻觉下的带毒夺冠”。
