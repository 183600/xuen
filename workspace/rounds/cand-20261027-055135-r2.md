# 第 8 轮 · PAIR：成功率先行，步级反事实恢复，人形双臂角色

> 检索/复核日期：**2026-10-27（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「人形机器人」「对比实验」「闭环控制」。

本轮先纠正上一轮的一个硬错误：**排行榜不是「成功率与步骤分综合排序」，而是成功率先行、步骤分只在成功率相同时破平，最后才看提交日期。** 这不是措辞差异，而是目标函数变了——上一轮 PILOT-GPR 把大量预算押在「终局放置 + 步骤分」上，方向仍然有价值，但**不能把步骤分当成可加权的主目标**。新的主判断是：

> **在 320 trials、成功率先行的赛制下，最高杠杆不是再换一个更大的 VLA，而是在冻结 VLA 外面加一层「步级失败验证 + 人形双臂恢复」：用成对反事实训练一个小的失败验证器，在 chunk 边界决定继续/回退/重抓/换手/重放；终局放置只是这个恢复层的一个特例。**

## 0. 本轮先核实：八个事实

### 0.1 排名规则：成功率先行，步骤分只破平

中文手册原文：「实时榜单按32个任务的 **总平均成功率** 进行排序，成功率相同时按 **总平均步骤分** 排序，若仍相同，则提交日期较早的模型排序靠前。」英文版同义。这确认了三件事：

1. 成功率是唯一主目标；步骤分是 tie-breaker，不是可交换的分数。
2. 任何一步失败 = 整个 episode 失败；不存在「前面多拿分、后面失手也能补」。
3. 提交日期是第三 tie-breaker，说明头部会非常拥挤，**晚上线不如早上线**。

### 0.2 每个任务 10 次，5 类泛化各 2 次，共 320 trials

手册：每个任务 10 次独立运行，包含位置、干扰物、桌面背景、未见物品、人为干扰 5 类，各 2 次。32×10=320。这是统计功效的硬约束（见 0.3）。

### 0.3 公开榜单仍是占位，头部差异不可分

`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，页面仍是「Coming Soon」。8 个占位模型：

| 模型 | 成功率 | 步骤分 | 差 |
|---|---:|---:|---:|
| MolmoAct2 | 29.7 | 39.0 | 9.3 |
| WALL-OSS-0.5 | 28.5 | 38.9 | 10.4 |
| DreamZero | 27.9 | 37.9 | 10.0 |
| Spirit-v1.5 | 25.9 | 34.4 | 8.5 |
| DM0 | 23.5 | 31.7 | 8.2 |
| PI-0.5 | 22.8 | 30.6 | 7.8 |
| GigaBrain-0 | 22.6 | 29.5 | 6.9 |
| GR00T N1.5 | 20.5 | 28.1 | 7.6 |

这些数字与用户「榜首不到 30%」量级一致，但**不是真实榜单**，只能当弱先验。320 trials、p≈0.30 时 SE≈2.56pp，95% CI≈±5.0pp；榜首 29.7 与第二 28.5 只差 1.2pp，独立两比例检验的 SE≈3.6pp，完全不显著。**头部是统计意义上的平局，不能从占位榜推断「哪种架构赢了」。** 对头部的正确读法是：前四名只差 3.8pp、8 个模型全部落在 ±5pp CI 内，没有证据表明 VLA / world model / hybrid 中某一类领先；可学的不是某个具体模型的结构，而是它们共同缺的运行时可靠性。

### 0.4 占位任务均值也是脚本生成，不能用来推断真实失败分布

把 8 个占位模型按任务平均后，任务成功率与「步骤分−成功率」的相关系数高达 **r≈0.999**；也就是说，gap 几乎是成功率的线性函数。这是脚本生成的痕迹，不是真实任务结构。上一轮曾据此推断「低成功率任务失败早、高成功率任务失败晚」，本轮必须撤回：**占位数据只能说明量级，不能说明失败发生在哪一步。**

### 0.5 提交接口的 chunk 是「整段执行」，闭环只能发生在 chunk 边界

提交 README 原文：`action_chunk_size` 是每次 `get_action` 返回的动作步数；「index 0 is executed first, then the rest in order, until the evaluator calls `get_action` again.」这意味着：

- 评测器执行完整 chunk 后才会给下一次观测；
- 策略不能在 chunk 内部逐步重规划；
- 闭环频率 = 1 个 chunk，而不是 1 个控制步；
- `action_chunk_size` 是提交级固定值，不能按任务/阶段动态切换。

上一轮「自由空间长 chunk、接触段短 chunk」在 API 上不成立，必须改成：**固定 T_a + chunk 内相位速度曲线 + chunk 边界验证/恢复**。

### 0.6 `action.pivot` 存在，但语义只公开了一半

每个 action chunk 必带共享 `action.pivot` [7]，字段名 `[vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]`。挑战数据采样到的任务里，`action.pivot` 都是常量 `[0,0,0,0,0.15,0,0.74]`；`waist_state_joint` 会小幅变化。`pivot_3..5` 的语义官方未说明，可能是腰/躯干，但**不能默认可安全使用**。观测侧 `lower_body` [15] 含双腿 + 腰 yaw/roll/pitch，但没有 torso frame、没有 depth；头双 stereo 可估深度。结论：torso 只能作为「需标定的可选杠杆」，主押注不能建在它上面。

### 0.7 官方给了逐任务的人为干扰剧本，且多数是「中途撤销」

32 个 `tasks_v2/<slug>/info.json` 的 `generalization.human_1_note/human_4_note` 是逐任务备注，例如 T27「叠了第二个之后拿下第二个」、T19「拉上拉链之后拉开」、T14「拧开盖子之后拧动回来」、T10「将插头拔起」、T24「可乐快到了然后放回传送带起点」。这不是背景噪声，而是**评测方主动制造的 mid-episode undo**。它直接证明：只做「终局放置」不够，必须在 episode 中途检测并恢复。

### 0.8 数据、复述、调试通道与规则盲区

- 数据集约 33k episodes / 169h / 30fps / 四路相机；每任务约 1k 条；每任务 5 条英文复述（`@` 分隔），共 160 条指令。
- 平台有「不计分单任务调试」通道，可预约真实 G1 做 A/B。
- 手册 2.2 之后（外部数据、仿真、预训练权重规则）被 Feishu 懒加载截断，仍未读到；L2L 外部数据默认 OFF。
- 直连 unibot.unitree.com 有反爬，需 `https://r.jina.ai/` 前缀。

## 1. 三个灵感词，各自钉到事实上

### 1.1 人形机器人：不是「双臂的机械臂」，而是「角色分工 + 支撑 + 躯干」

G1 的 32 个任务里，约 15 个需要或强受益于双手协作：T05 按住网口再拔线、T10 按住插排再插插头、T12 按住锁再转钥匙、T14 按住瓶身再拧盖/倒药、T16 叠毛巾、T17/T19/T23/T31 一只手固定包/盒、另一只手拉拉链或放物品、T26 按住端口再插网线、T28 耳机盒与盖子、T29 盒子与托盘、T32 注射器与杯子。**这些任务的失败往往不是「抓不到」，而是角色冲突：两只手都想去操作，没人稳定支撑；或者稳定手先松了。**

人形证据：

- **POT-VLA**（G1，2026-07）把持久 3D object tokens 同时用于动作条件和几何谓词校验，匹配 GR00T-N1.7 基线 39/80→71/80；其中 **verifier-only 就把 4 个困难任务从 15/40 提到 22/40（+17.5pp）**，full 34/40。说明「动作之外的状态校验/重试」本身就有大收益。
- **SHS**（G1，2026-09）让一只手撑住环境、另一只手发力，可用接触力从 13.5N 提到 60N。说明「支撑手」不是礼貌动作，而是力学能力。
- **Dual-Level Bimanual**（2026-06）用 view-selective router + interaction-aware action MoE，仿真 +27.7%、真机 +43.3%。说明双臂角色结构是有效的归纳偏置。
- **HAF-VLA**（2026-08）把 humanoid 动作分成 locomotion/head → torso → bimanual 三段。说明躯干是独立控制阶段，但我们的 API 只暴露了部分 pivot，需谨慎。

### 1.2 对比实验：不是「多跑几组」，而是「成对反事实 + 步隔离 + 失败注入」

320 trials 的统计功效决定了：**不能靠 leaderboard 上 1–2pp 的差异做决策**。必须用成对设计：

- **成对反事实（paired counterfactual）**：同一初始状态，baseline 与 full 各跑一次；比较配对差值，而不是两个独立均值。
- **步隔离（step isolation）**：用 oracle/演示替换某一步，测「只改这一步」对整条 episode 的边际成功率；用来判断钱该花在哪一步，而不是拍脑袋。
- **失败注入（failure injection）**：按官方 human 备注构造「中途拿走/拉回/移动」脚本；测验证器能否在失败扩散前发现，以及恢复能否接上。
- **2×2×2 消融**：验证器（有/无）× 恢复（有/无）× 双臂角色路由（有/无），至少 8 格；再看 chunk 大小、stereo 深度、终局模块。
- **统计**：320 trials、p≈0.30 时 95% CI≈±5pp；+5pp 在独立两比例下只有约 27% power，+10pp 约 75%，+15pp 才稳。所以主目标应定 **+10pp 量级**，并把「+5pp 以下不宣称」写进预注册。

### 1.3 闭环控制：不是「每步闭环」，而是「chunk 边界闭环 + chunk 内相位曲线」

API 限制决定了闭环的形态：

- **边界**：每个 chunk 结束拿一次新观测；验证器在这里判断 `continue / hold / backtrack / regrasp / re-place / role-swap / re-anchor`。
- **chunk 内**：不能重规划，但可以设计相位速度曲线（自由空间快、接触段慢、终局 settle），把「慢」放在最容易失败的地方。
- **固定 T_a**：不能按任务切换；用 4 或 8 做全局折中，配合 RTC 式边界混合，避免 chunk 切换抖动。
- **时间预算**：180s 很宽；一次恢复 2–4s，最多 2 次，仍只占 5% 左右。真正的约束是「恢复不能把已经完成的前序步骤弄坏」。

## 2. 主判断：从「终局放置闸门」升级为「步级恢复层」

### 2.1 为什么终局放置仍然重要，但不能当唯一主线

终局步骤仍是 32/32 任务的成功闸门，终局权重合计 1275/3200=39.8%，放置/插入/堆叠/闭合类约 59.7%。这些事实不变。但三个新事实把它从「唯一主线」降为「主线的一半」：

1. **成功率先行**：终局成功只是最后一步；前面的步骤失败同样直接归零。步骤分不再是可加权补偿。
2. **官方干扰是中途 undo**：T19 拉上后再拉开、T27 叠好后再拿走、T14 拧开后拧回。终局放置无法处理「已经完成又被撤销」。
3. **约 15 个双手任务**：失败常发生在角色分工/支撑/换手，而不是最后的落点。

所以正确的结构是：**步级恢复层是主干；终局放置（PGL/OPT/ICR/SVL）是其中一个高价值子模块，专门处理「最后 3 厘米」和「放完不稳定」。**

### 2.2 一个新的失败模型：失败会沿步骤链传播

| 编号 | 失败模式 | 典型任务 | 现有模型为什么不行 | 对策 |
|---|---|---|---|---|
| F1 | 目标/落点 grounding 错 | T07/T20/T21/T27 | 语言到坐标的 grounding 在 OOD 下漂移 | 立体深度 + 关系锚点 + 谓词校验 |
| F2 | 双臂角色冲突 | T10/T12/T14/T19/T26/T31 | 单策略把两只手当独立末端，没人稳定 | 角色路由 + 支撑手先验 |
| F3 | 接触/插入不稳定 | T10/T14/T26/T32 | 开环 chunk 无法感知卡阻/滑移 | 慢接触段 + 力/位姿代理 + 回退 |
| F4 | 布料/透明/小件感知弱 | T14/T16/T19/T31 | RGB 单目 + 无触觉 | 立体 + 相位先验 + 降级策略 |
| F5 | 人为干扰/undo | T10/T12/T14/T19/T24/T27 | 训练分布里没有「做完再被撤销」 | NRB-2 失败注入 + 重定位 |
| F6 | 假完成/不验证 | 全部 | 策略输出动作，不校验物理结果 | CCV + 几何谓词 + 重试 |
| F7 | 恢复本身把局面弄坏 | 全部 | 无恢复，或恢复太粗暴 | 预算/安全壳 + 回退到安全位姿 |

这张表的关键不是「七个都做」，而是：**F2/F5/F6 是上一轮没有充分覆盖的，而它们恰好是成功率先行赛制下最伤的三类。**

### 2.3 与第 7 轮 PILOT-GPR 的关系

- **保留**：GPR-VLA 主干、WLA-1.0-Base、TLE/ACP/GF、AH-TP、Endurance Governor、Compliance Compiler、SSG、PGL、OPT、ICR、SVL、NRB、L2L、DebugLoop、FLEET 检查单。
- **升级**：SSG → **SGG-2**（从「步骤分预算」改为「步骤诊断 + 验证器标签」）；SVL → **SLR**（从「终局 settle」改为「步级恢复原语」）；NRB → **NRB-2**（官方备注 + undo + 失败注入）。
- **新增**：**CCV**（成对反事实对比验证器）、**BRR**（双臂角色路由）、**TCE**（torso 规范化/可选主动躯干）、**ACR**（固定 chunk + RTC 边界混合）、**PCE**（成对反事实实验协议）。
- **降级**：PGL/OPT/ICR 从「主武器」降为「终局子图」；FLEET 只做工程检查单；TCLB 只做离线相对比较。
- **砍**：全 32 任务高保真孪生、自由仿真数据、运行时仿真/MPC、仿真 RL、布料/拉链/透明全物理、WMA-0 进主路径、每任务 LoRA/模型合并。

## 3. 方案轮廓：PAIR-GPR

```text
指令(160条复述) ──► SGG-2 步骤图/谓词 ──► 当前步骤 s、相位 φ
                                      │
                     ┌────────────────▼────────────────┐
                     │ CCV 成对反事实验证器             │
                     │ 输入: VLA 内部特征 + 立体深度摘要 │
                     │       + 本体 + 步骤/语言          │
                     │ 输出: p_fail, 失败步骤, 恢复价值  │
                     └────────────────┬────────────────┘
                          p_fail < τ │ p_fail ≥ τ
                                    │
              ┌─────────────────────┴─────────────────────┐
              ▼                                           ▼
   GPR-VLA + BRR 双臂角色路由                 SLR 恢复原语
   （唯一学习 checkpoint）                    hold/backtrack/regrasp/
              │                                re-place/role-swap/re-anchor
              ▼                                           │
        动作 chunk（固定 T_a）                            │
              │                                           │
              └────────────► 评测器执行整段 ◄──────────────┘
                                      │
                              下一 chunk 边界观测
                                      │
                                      └──► CCV 再判断
```

**PAIR** = **P**aired counterfactual **A**udit + **I**n-episode **R**ecovery。四个关键词：成对反事实、步级、双臂角色、chunk 边界闭环。

一句话：**冻结的 VLA 负责「怎么做」，CCV 负责「现在做得对不对」，SLR 负责「不对时怎么救」，BRR 负责「两只手谁主谁辅」。**

## 4. 预期收益与证伪

设 baseline 每步成功率 p、平均步数 n=2.94；整体成功率 P=p^n=0.30 ⇒ p≈0.664。设失败步被 CCV 发现概率 d、恢复成功率 r，则每步失败率从 (1−p) 降为 (1−p)(1−dr)，新整体成功率：

```text
P' = [1 − (1−p)(1−dr)]^n
```

粗算（上限模型，不含误报/耗时惩罚）：

| d | r | dr | P' | 增益 |
|---:|---:|---:|---:|---:|
| 0.4 | 0.3 | 0.12 | 0.357 | +5.7pp |
| 0.5 | 0.4 | 0.20 | 0.398 | +9.8pp |
| 0.6 | 0.5 | 0.30 | 0.455 | +15.5pp |
| 0.7 | 0.6 | 0.42 | 0.529 | +22.9pp |

所以项目目标定 **+10pp 量级**（成功率 30%→40% 左右），而不是 +3pp。**证伪条件**：若 CCV 在 held-out 场景 AUROC<0.70，或恢复成功率<30%，或误报导致净增益<3pp，则关掉 SLR，回退到「PGL/OPT 终局子图 + 几何谓词」；若双臂角色路由在 5 个双手任务上无增益，则删掉 BRR。

## 5. 风险与合规

- **手册未读部分**：外部数据/仿真/预训练权重规则未知；L2L 默认 OFF，只做协议与法务准备。
- **单模型审计**：CCV/BRR 都是同一 checkpoint 内的头；立体深度用经典 SGBM，不引入第二个学习模型；若官方把任何辅助模型都视为第二模型，关掉深度/检测，退回 RGB-only。
- **pivot 未标定**：默认常量 `[0,0,0,0,0.15,0,0.74]`；TCE 只在调试槽确认语义后开，且只做小范围高度/腰角。
- **chunk 延迟**：T_a 固定；先 benchmark p99；若 p99>200ms，降 T_a 或量化/蒸馏，不用重检索。
- **恢复反噬**：每次 episode 最多 2 次恢复，预算 20% 时间；恢复前先回安全位姿；连续两次失败则放弃当前步，回退更远。
- **统计噪声**：320 trials；预注册主终点（成功率）；+5pp 以下不宣称；用配对 bootstrap，不用独立均值。
- **调试槽稀缺**：每个大版本最多 1 槽；T27/T10/T19/T24 轮换；A/B/A 设计。

## 6. 一句话押注

**把「成功率先行」当第一性约束：在冻结 VLA 外面加一层用成对反事实训练的步级失败验证器，在 chunk 边界触发人形双臂角色重分配与恢复原语；终局放置只是这个恢复层的一个高价值特例。**

# 第 8 轮产物区 · PAIR-GPR 技术报告（成功率先行 + 步级反事实恢复 + 人形双臂角色）

## 0. 产物摘要

### 0.1 一句话

**在冻结 VLA 外面加一层用成对反事实训练的步级失败验证器（CCV），在 chunk 边界触发人形双臂角色重分配（BRR）与恢复原语（SLR）；终局放置只是这个恢复层的一个高价值特例。**

## 1. 事实核对（本轮新增，全部一手；来源表见 §12）

### 1.1 排名规则：成功率先行

中文手册 [S1] 原文：

> 实时榜单按32个任务的 **总平均成功率** 进行排序，成功率相同时按 **总平均步骤分** 排序，若仍相同，则提交日期较早的模型排序靠前。

英文版 [S2] 同义。由此：

1. 成功率是主目标；步骤分是 tie-breaker。
2. 任何一步失败 = episode 失败；不存在「多拿步骤分补成功率」。
3. 提交日期是第三 tie-breaker；头部拥挤时，早提交有优势。

### 1.2 每个任务 10 次，5 类泛化各 2 次

手册 [S1]：每个任务 10 次独立运行，包含位置、干扰物、桌面背景、未见物品、人为干扰 5 类，每种各 2 次。32×10=320 trials。单任务不计分调试通道存在，但结果不进排行榜。

### 1.3 公开榜单仍是占位

`leaderboard_data.json` [S9] 的 `generated_from` 仍是 `gen_leaderboard.py`；页面 [S10] 仍是「Coming Soon」。8 个占位模型：

| 模型 | 成功率 | 步骤分 | 步骤分−成功率 | 平均时长(s) |
|---|---:|---:|---:|---:|
| MolmoAct2 | 29.7 | 39.0 | 9.3 | 44.02 |
| WALL-OSS-0.5 | 28.5 | 38.9 | 10.4 | 43.74 |
| DreamZero | 27.9 | 37.9 | 10.0 | 44.59 |
| Spirit-v1.5 | 25.9 | 34.4 | 8.5 | 45.19 |
| DM0 | 23.5 | 31.7 | 8.2 | 45.11 |
| PI-0.5 | 22.8 | 30.6 | 7.8 | 43.88 |
| GigaBrain-0 | 22.6 | 29.5 | 6.9 | 43.76 |
| GR00T N1.5 | 20.5 | 28.1 | 7.6 | 44.71 |

均值：成功率 25.2%，步骤分 33.8%，差 8.6pp。**这不是真实榜单；只能当「模型大概在 20–30% 成功率」的弱先验。** 前四名只差 3.8pp，8 个模型全部落在 ±5pp CI 内；没有证据表明 VLA / world model / hybrid 中某一类领先。可学的不是某个具体模型的结构，而是它们共同缺的运行时可靠性。

### 1.4 占位任务均值是脚本生成，不能推断失败分布

把 8 个占位模型按任务平均后：

- 最低：Plug In Ethernet 17.7/23.7；Unlock 20.1/26.9；Spell robot 21.8/29.3；Organize Stationery 22.5/30.1；Open Pill Bottle 22.7/30.5。
- 最高：Stack Cups 30.3/40.6；Conveyor 29.1/39.0；Paper Cup Stacking 28.0/37.6；Place Photo Frames 28.0/37.5；Store Earphones 27.9/37.4。
- 任务成功率与 gap 的相关系数 **r≈0.9991**；gap 几乎是成功率的线性函数。这是脚本生成痕迹，不是真实任务结构。

因此本报告**不使用占位任务均值推断「哪一步失败」**；只使用「量级」和「步骤分通常高于成功率」这一弱事实。真实失败分布必须靠离线标注 + 调试槽建立。

### 1.5 提交接口：chunk 整段执行，闭环在边界

提交 README [S8] 原文：

> `action_chunk_size` ... is the number of action steps returned each time. ... index `0` is executed first, then the rest in order, until the evaluator calls `get_action` again.

约束：

- 评测器执行完整 chunk 后才给下一次观测；chunk 内不能重规划。
- `action_chunk_size` 是提交级固定值；不能按任务/阶段动态切换。
- 闭环频率 = 1/T_a；不是 1 个控制步。
- 评测器记录每步延迟与动作统计；延迟不稳会影响可信度 [S8]。

### 1.6 观测与动作：4 路 RGB、无 depth、pivot 半公开

观测 [S8]：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 480×640；双臂 7 维关节/EE base；夹爪 1 维；`lower_body` 15 维（双腿 + 腰 yaw/roll/pitch）；语言单字符串。**没有 depth、没有 torso frame、没有力/触觉。**

动作 [S8]：`joint` 或 `ee` 互斥；共享 `action.pivot` [7] 必带；`action_chunk_size` 固定；`obs_delta_indices` 决定传哪些键和堆叠帧；`image_resize` 可缩放。

数据卡 [S6] 给出 `pivot` 字段名 `[vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height]`；挑战数据采样任务里 pivot 常量 `[0,0,0,0,0.15,0,0.74]`，`waist_state_joint` 小幅变化。`pivot_3..5` 语义未公开。**默认常量 pivot；TCE 主动躯干只在调试槽标定后开。**

### 1.7 数据、复述、官方干扰剧本、调试通道

- 数据集 [S3][S4]：32 repo、约 33k episodes、169h、30fps、LeRobot v3；四路相机；EE base/torso、waist/legs。
- 每任务 5 条英文复述（`@` 分隔），共 160 条 [S5]。
- 每任务 `info.json` [S2] 有 `generalization.human_1_note/human_4_note`，多为「中途移动/拿走/撤销」；完整表见附录 B。
- 平台有「不计分单任务调试」通道 [S9]，可预约真机 A/B。
- 手册 2.2 之后（外部数据/仿真/预训练权重）被 Feishu 懒加载截断；本报告标「未核实」，L2L 默认 OFF。

## 2. 评分算术与统计功效

### 2.1 字典序排名，不是加权和

排名是：

```text
rank_key = (总平均成功率, 总平均步骤分, 提交日期)
```

不是 `α·成功率 + β·步骤分`。因此：

- 不要做「牺牲一点成功率换很多步骤分」的优化；
- 步骤分只在成功率完全相同时才影响排名；
- 任何「让 episode 成功」的改进都优先于「让失败 episode 多做几步」。

### 2.2 baseline 的每步成功率

32 任务平均 2.94 步；整体 0.30 ⇒ 每步 p=0.30^(1/2.94)≈0.664。若用占位均值 0.252，则 p≈0.624。后续用 0.65 做近似。

### 2.3 恢复层的上限模型

```text
P' = [1 − (1−p)(1−dr)]^n
```

其中 d=失败步被 CCV 发现概率，r=恢复成功率。粗算：

| d | r | dr | P' | 增益 |
|---:|---:|---:|---:|---:|
| 0.4 | 0.3 | 0.12 | 0.357 | +5.7pp |
| 0.5 | 0.4 | 0.20 | 0.398 | +9.8pp |
| 0.6 | 0.5 | 0.30 | 0.455 | +15.5pp |
| 0.7 | 0.6 | 0.42 | 0.529 | +22.9pp |

这是上限模型，不含误报、恢复耗时、恢复反噬。实际目标 +10pp 是合理的中间值。

### 2.4 320 trials 的统计功效

- p≈0.30，n=320：SE=√(0.3×0.7/320)=2.56pp；95% CI≈±5.0pp。
- 两个独立模型各 320：差 1.2pp 的 SE≈3.6pp；z≈0.33，不显著。
- +5pp：独立两比例、双侧 5%、80% power 需要约 1,300/trial 组；320 只有约 27% power。
- +10pp：约 75% power；+15pp：>95%。

结论：**不要把 +1–3pp 当成果；主目标 +10pp；能用配对设计就用配对设计（同任务/同初始状态/同种子）。**

### 2.5 为什么终局放置是子图，不是全部

- 终局仍是成功闸门：32/32 任务最后一步；终局权重 1275/3200=39.8%。
- 放置/插入/堆叠/闭合类约 1910/3200=59.7%。
- 但官方 human 备注是中途 undo；约 15 个双手任务失败在角色/支撑；终局模块无法覆盖这些。
- 因此：**SLR 是主干，PGL/OPT/ICR/SVL 是终局子图。** 终局子图仍保留，因为它在 T20/T21/T25/T27 等「最后 3 厘米」任务上仍是最高杠杆。

## 4. PAIR-GPR 架构

### 4.1 总览

```text
语言(160复述) ──► SGG-2 步骤图/谓词 ──► 步骤 s、相位 φ、完成谓词 c
                                      │
                     ┌────────────────▼────────────────┐
                     │ CCV: p_fail, step, recovery value│
                     │ VLA 特征 + stereo depth + proprio│
                     └────────────────┬────────────────┘
                          p_fail < τ │ p_fail ≥ τ
                                    │
              ┌─────────────────────┴─────────────────────┐
              ▼                                           ▼
   GPR-VLA + BRR 角色路由                     SLR 恢复原语
   （唯一学习 checkpoint）                    hold/backtrack/regrasp/
              │                                re-place/role-swap/re-anchor
              ▼                                           │
        固定 T_a 动作 chunk ──► 评测器整段执行 ────────────┘
                                      │
                              下一 chunk 观测
                                      │
                                      └──► CCV 再判断
```

### 4.2 SGG-2：步骤图/谓词（保留，降级）

- 从 `info.json` 的 `score_steps` 建 32 个任务图；每步一个节点，边是「完成谓词」。
- 语言匹配覆盖 32×5=160 条复述；用 embedding 兜底。
- 输出：当前步骤 s、相位 φ（approach/contact/close/release）、谓词 c。
- 用途：CCV 的步骤标签、SLR 的恢复目标、离线诊断；**不再用于「按步骤权重分配重试预算」**。
- 谓词头：小 MLP/线性头，输入 VLA 特征 + 物体关系；用演示状态标签训练；F1 校准。
- 风险：谓词噪声；用双阈值 + 人工抽检；若 F1<0.8，退回纯步骤标签。

### 4.3 CCV：成对反事实对比验证器（新增，主押注）

**输入**：

- VLA 最后一层/动作专家隐藏特征（冻结或轻量适配）；
- 立体深度摘要（SGBM 视差 → 前景物体/容器相对位姿；不用第二个学习模型）；
- 本体：双臂 EE、夹爪、`lower_body`；
- 步骤 s、相位 φ、语言 embedding；
- 历史：最近 2–3 个 chunk 的特征/动作。

**输出**：

- `p_fail`（当前 chunk 后失败概率）；
- 失败步骤/相位分类；
- 恢复价值 `V(recover) − V(continue)`（可选）；
- 校准温度（post-hoc）。

**训练信号**：

1. **成对反事实**：同一任务/步骤，成功 rollout 与失败 rollout 的特征对；pairwise ranking loss + BCE。
2. **官方备注失败注入**：NRB-2 生成「中途拿走/拉回/移动」的失败；标签为失败步骤。
3. **自然失败**：33k 演示里的重试/失败片段；挖掘 hard negatives。
4. **假完成负例**：谓词未满足但策略停下的片段；这是 F6 的关键负例。

**损失**：

```text
L_CCV = BCE(p_fail, y) + λ1·PairRank(f_succ, f_fail) + λ2·CE(step) + λ3·Calibration
```

**与 Backtrack 的差异**：Backtrack 是 episode 级失败头 + 回退最近运动，只用 0.48–0.88% 参数就把 LIBERO-Long 成功率最高提了 +7.4pp；CCV 是**步级 + 成对反事实 + 多模态 + 双臂角色**。**与 POT-VLA 的差异**：POT 用几何谓词 + RGB-D + SAM3；CCV 用学习验证器 + 立体 + 单模型；POT 的 verifier-only +17.5pp 是我们最接近的先验，但不是同一个方法。

**验收**：held-out 场景 AUROC≥0.80、AUPRC≥0.70、固定 recall 下误报≤15%、检测延迟≤1 chunk。达不到就降级为「几何谓词 + 规则」。

### 4.4 SLR：步级恢复原语（升级 SVL，主押注）

| 原语 | 触发 | 动作 | 适用 |
|---|---|---|---|
| `continue` | p_fail<τ | 正常 chunk | 大多数 |
| `hold` | 滑移/未稳/遮挡 | 停 0.2–0.5s，重新观测/等 settle | T20/T27/T32 |
| `backtrack` | 刚进入坏状态 | 回退最近 k 步到安全位姿，再让策略重试 | F3/F6 |
| `regrasp` | 抓取不牢/错位 | 张开→后退→重新接近→闭合 | T01/T08/T13 |
| `re-place` | 落点/姿态错 | 抬起→重对锚点→缓放 | T07/T20/T21/T25/T27 |
| `role-swap` | 角色冲突/支撑手先松 | 交换 stabilize/manipulate，重新夹持 | T10/T12/T14/T19/T26/T31 |
| `re-anchor` | 目标被移动/undo | 重新检测容器/目标，刷新深度/相对位姿 | F5 全部 |
| `torso-adjust` | 够不到/看不见 | 小范围腰/高调整（需标定） | 可选，默认关 |

**选择策略**：先规则（按失败步骤/相位/角色），再用小价值头在 2–3 个候选里选；训练用 NRB-2 的恢复对 + 演示里的自然重试，做 filtered BC，不做 RL。

**预算**：每 episode 最多 2 次恢复；每次≤4s；总恢复时间≤20%×180s；连续两次失败→回退更远/放弃当前步。

**安全壳**：动作限幅、关节限位、速度限制、pivot 常量；恢复前先回安全位姿；不移动 base。

### 4.5 BRR：双臂角色路由（新增，主押注）

**角色定义**（每臂）：

- `stabilize`：夹住/按住物体或容器，末端速度低，夹爪闭合；
- `manipulate`：抓取/插入/拉链/倾倒，末端运动/夹爪动作；
- `idle`：不参与。

**标签**：从演示自动标注——夹爪闭合 + EE 速度低 + 另一臂运动 ⇒ `stabilize`；夹爪动作/EE 速度高 ⇒ `manipulate`；其余 `idle`。按 chunk 聚合，人工抽检 5%。

**模型**：在动作专家上加角色 token（2×3 类）与 FiLM/AdaLN 条件；或两个动作头 + 门控。**全部在同一 checkpoint 内**，不引入第二个模型。

**推理**：角色分类器输入语言/步骤/视觉/本体；带迟滞（最短 0.3s）与置信阈值；低置信时用「任务/步骤的演示角色先验」。

**为什么有效**：

- Dual-Level Bimanual：双臂结构 +27.7% 仿真、+43.3% 真机；
- SHS：支撑手把可用力从 13.5N 提到 60N；
- POT：bimanual handling 是最大增益任务族之一。

**验收**：5 个双手任务上角色准确率≥80%；相对无 BRR 的成功率 +3pp 以上；角色切换次数≤2/任务。

### 4.6 TCE：torso 规范化 + 可选主动躯干（新增，可选）

- 用 `lower_body` 的腰 yaw/roll/pitch + 数据集的 `state_torso`/`waist_state_joint` 拟合 FK，重建 torso 系。
- 训练时把 EE 目标/观测 canonicalize 到 torso 系；动作输出再转回 base。目的是跨底座/腰高变化稳定，而不是主动运动。
- 主动躯干：仅当调试槽确认 `action.pivot` 的 `pivot_3..5` 语义后，做小范围高度/腰角调整；默认常量 pivot。
- 验收：canonicalization 使 EE 位姿误差下降；主动躯干在 2 个高/低任务上 +2pp 才保留。
- 风险：pivot 语义错 → 机器人异常；默认关；需要急停/限幅。

### 4.7 ACR：固定 chunk + RTC 式边界混合（新增，工程必要）

- `action_chunk_size` 固定；默认 **T_a=8**，延迟允许则 4。
- chunk 内：相位速度曲线（transit 快、contact 慢、release settle）；夹爪时序单独参数化。
- 边界：新 chunk 前 k 步从上一 chunk 最后指令平滑过渡（RTC 式 blending），减少抖动。
- 不用「按任务切换 chunk」；如果必须变，只能在提交级选一个全局值。
- 延迟目标：p99≤150ms；超过则量化/蒸馏/减观测，不用重检索。

### 4.8 NRB-2：官方备注恢复库（升级）

- 把附录 B 的 human_1/human_4 备注转成场景脚本：移动/拿走/拉回/拔起/打开。
- 每条脚本生成「破坏前→破坏→恢复」三元组；恢复目标由 SGG-2 谓词定义。
- 加入「做完再撤销」的 undo 对：T19 拉链拉开、T27 拿走碗、T14 拧回瓶盖、T17 打开笔盒、T10 拔起插头。
- 数据量：32 任务 × 2 备注 × 50 = 3,200 对；加通用扰动 2,000 对。
- 用途：CCV 失败标签 + SLR 恢复 BC + BRR 角色冲突样本；不直接进推理。

### 4.9 GPR-VLA + WLA（保留）

- 唯一学习主干：语言/目标 → 残差 → 动作专家 → chunk。
- 接入 CCV 的 `p_fail`（stop-gradient 或轻量适配）、BRR 的角色 token、SLR 的恢复目标。
- 保持 Apache-2.0 许可与单卡可微调；训练用 LoRA/部分解冻，推理量化。

### 4.10 接口与损失

| 项 | 含义 | 起始权重 |
|---|---|---:|
| L_act | 演示动作/EE 目标 | 1.0 |
| L_step | SGG-2 谓词 BCE | 0.2 |
| L_role | BRR 角色 CE | 0.1 |
| L_ccv | CCV BCE + pairwise | 0.3 |
| L_rec | SLR 恢复 BC/偏好 | 0.2 |
| L_cal | CCV 温度/校准 | 0.05 |

训练顺序：先 L_act+L_step，再 L_role，再冻结主干训 L_ccv，最后联合轻调 L_rec；避免 CCV 把主干特征拉坏。

## 5. 闭环控制在 UniBot API 上的落法

### 5.1 chunk 是硬边界

评测器执行完整 chunk 才调用下一次 `get_action`；因此：

- 不能在 chunk 内根据新观测改动作；
- 验证/恢复只能发生在 chunk 边界；
- `action_chunk_size` 是提交级固定值；
- 评测器记录延迟/动作统计，异常会进可信度评估。

### 5.2 T_a 选择

| T_a | 边界频率（30Hz 假设） | 优点 | 风险 |
|---:|---:|---|---|
| 1 | 30Hz | 最大闭环 | 调用太多，延迟/抖动 |
| 4 | 7.5Hz | 较快闭环 | 推理压力 |
| 8 | 3.75Hz | 平衡 | 失败可能晚 0.27s 才发现 |
| 16 | 1.9Hz | 稳定 | 接触段太开环 |

默认 T_a=8；用 `run_client` 压测 p50/p99 后再定。若 p99>150ms，保持 8 并量化；若 p99<80ms，试 4。

### 5.3 观测配置

- 高位双目：`[-8,-4,0]` 三帧，240×320；用于 stereo/场景。
- 腕部：`[-4,0]` 两帧，240×320；用于接触/插入。
- 本体：`[-8,-4,0]`；语言：`[0]`。
- `image_resize` 只用高位/腕部需要的键；不传无关键以降延迟。
- stereo：用数据集标定的双目内参/基线做 SGBM；不引入深度模型。若标定不可用，深度只做相对特征，不做度量。

### 5.4 时间预算

- 180s/任务；典型演示 6–45s；恢复 2–4s/次，最多 2 次。
- 预算守卫：`t_elapsed + t_recovery > 0.8×180` 时禁止恢复，只做保守 continue。
- 长任务（T16/T17/T31）优先 `hold/backtrack`，少 `re-place`。

### 5.5 安全壳

- 关节/EE 目标限幅；速度限制；夹爪力/开度限幅（API 只给位置，保守）。
- pivot 默认常量；TCE 主动躯干必须限幅 + 急停。
- 恢复前回安全位姿；不移动 base；不把物体举高过肩。
- 失败注入/恢复数据训练时加入「恢复反噬」负例。

### 5.6 N 端口与状态隔离

- 官方按 N 台机器人随机顺序评测；每台固定端口，从 8765 连续 N 个。
- 每端口独立 `reset`/历史/缓存；共享模型时用请求队列 + 状态隔离，避免跨 episode 污染。
- 共享后端要并发；不同端口可能同时调用。
- 健康检查 `/healthz`；延迟平滑；避免超时。

## 6. 人形双臂：从「双手」到「角色」

### 6.1 哪些任务真正需要双手

按步骤描述推定，约 15 个任务需要或强受益于双手协作：

- 按住/稳定 + 操作：T05、T10、T12、T14、T26、T28、T29、T32；
- 固定容器/包 + 放/拉：T17、T18、T19、T23、T31；
- 布料/大件：T16；
- 其他可能受益：T07、T09。

这些任务的共同点：**一只手必须牺牲自由度去稳定，另一只手才能精细操作。** 单策略如果不知道谁稳定、谁操作，就会两只手都去抓，或者稳定手提前松。

### 6.2 角色标签

自动规则（按 chunk）：

```text
if gripper_closed and ee_speed < v0 and other_arm_moving: role = stabilize
elif gripper_action or ee_speed > v1: role = manipulate
else: role = idle
```

人工抽检 5%；对 T10/T12/T19/T26/T31 重点复核。标签噪声大时，退化为「哪只手臂在动」的二分类。

### 6.3 角色路由

- 输入：语言/步骤 + 双目场景 + 双臂本体 + 上一 chunk 角色；
- 输出：2×3 角色 token；
- 条件化：FiLM/AdaLN 到动作专家；或用两个动作头 + 门控；
- 迟滞：最短 0.3s；切换需连续 2 个 chunk 置信；
- 低置信：用演示中该任务/步骤的角色先验。

### 6.4 支撑手/环境借力

- 对 T10/T12/T26：支撑手先夹住/按住底座，再让操作手插入/旋转。
- 对 T19/T31：支撑手固定包/盒，操作手拉拉链。
- 对 T16：双手折毛巾，角色随折叠阶段切换。
- SHS 证据：支撑手可把可用力从 13.5N 提到 60N；我们不做力控，但用「先稳定再操作」的时序先验。

### 6.5 torso 规范化

- FK 重建 torso 系：base → waist(yaw/roll/pitch) → torso。
- 训练时把 EE 目标/观测转到 torso 系；推理转回 base。
- 目的：跨底座高度/腰角稳定；不是主动运动。
- 主动躯干：默认关；调试槽确认 pivot 后，才做小范围高度/腰角。

### 6.6 评估

- 角色准确率；角色切换次数；双手任务成功率；物体滑移/掉落率；
- 对比：无 BRR、启发式 BRR、学习 BRR；
- 统计：配对任务/种子；5 个双手任务为主，不全 32 任务平摊。

## 7. 对比实验设计（本轮的方法论核心）

### 7.1 原则

1. **预注册**：主终点=成功率；次终点=步骤分、恢复率、误报率；不看完结果再改假设。
2. **配对**：同任务、同初始状态、同种子；baseline/full 交替；A/B/A 排除漂移。
3. **反事实**：不是「多跑几组」，而是「只改一个变量」；步隔离 + 失败注入。
4. **功效**：320 trials、±5pp CI；+5pp 以下不宣称；主目标 +10pp。
5. **不看榜调参**：公开榜是占位；真实榜发布后也只做验证，不做在线过拟合。

### 7.2 主实验

| ID | 配置 | 验证 | 预期 |
|---|---|---|---|
| E0 | GPR/WLA baseline | 复现；延迟/成功率 | 基线 |
| E1 | +SGG-2 | 步骤/谓词准确率 | 诊断，不涨点 |
| E2 | +CCV（只 hold/backtrack） | 检测 AUROC/误报；成功率 | +3–6pp |
| E3 | +SLR 全原语 | 恢复率；成功率 | +8–12pp |
| E4 | +BRR | 双手任务角色准确率/成功率 | +2–5pp |
| E5 | +ACR/RTC | 延迟/抖动；成功率 | 稳定性 |
| E6 | +TCE（可选） | torso 误差；主动躯干 | 0–2pp |
| E7 | 全量 + NRB-2 | 综合 | 目标 +10pp |

### 7.3 消融

| ID | 变量 | 对比 | 目的 |
|---|---|---|---|
| A1 | 验证器标签 | episode vs step vs 成对反事实 | 证明成对信号 |
| A2 | 恢复原语 | backtrack vs +regrasp vs +role-swap | 证明恢复组合 |
| A3 | 角色路由 | none vs heuristic vs learned | 证明 BRR |
| A4 | chunk | 1/4/8/16 | 延迟 vs 闭环 |
| A5 | 深度 | RGB vs stereo SGBM | 证明 stereo |
| A6 | 官方备注 | none vs NRB-2 | 证明 undo 数据 |
| A7 | 终局子图 | PGL/OPT on/off | 证明子图仍有价值 |
| A8 | 误报 | τ 扫描 | 找 operating point |

### 7.4 成对反事实 / 步隔离 / 失败注入

- **成对反事实**：同一初始状态，E0 与 E7 各跑；配对差值；bootstrap CI。
- **步隔离**：用 oracle/演示替换第 s 步，测整条 episode 的边际成功率；找出「最值钱的步骤」。在本地仿真/真机调试槽做，不在官方评测里做。
- **失败注入**：按附录 B 的 human 备注脚本，在本地/调试槽制造「拿走/拉回/移动」；测 CCV 检测时间、SLR 恢复率、恢复后是否二次失败。
- **恢复反噬**：故意在成功轨迹上触发恢复，测成功率下降；用于定 τ 和预算。

### 7.5 指标

- 成功率（主）；步骤分（次）；time-to-success；
- CCV：AUROC、AUPRC、固定 recall 下误报、检测延迟（chunk 数）；
- SLR：恢复触发率、恢复成功率、二次失败率、平均恢复耗时；
- BRR：角色准确率、切换次数、双手任务成功率、滑移/掉落；
- 系统：p50/p99 `get_action` 延迟、chunk 抖动、超时率；
- 安全：限幅触发、异常动作、pivot 越界。

### 7.6 调试槽

- 每个大版本最多 1 槽；任务轮换：T27（叠放+undo）、T10（插入+undo）、T19（拉链+undo）、T24（移动目标）、T05/T26（双手插入）。
- 设计：A/B/A；每个条件 2–3 次；记录视频/日志；只做相对比较，不做绝对结论。
- 发布门：调试槽成功率不低于 baseline；恢复无二次伤害；延迟稳定。

### 7.7 分析计划

- 主分析：配对成功率差 + bootstrap 95% CI；按任务分层（双手/非双手、刚体/布料）。
- 次分析：恢复率×检测率；误报代价；chunk/延迟。
- 负结果：如果 CCV 只在训练场景有效、OOD 崩，记录为「验证器过拟合」，回退几何谓词。
- 不调参：测试集只用于最终报告；调参用验证集/本地。

## 9. 创新点清单（动机/差异/可行性/资源/步骤/风险/状态）

> 状态：押注=本轮主线；保留=沿用；升级=旧点改造；降级=保留但非主回路；砍=不做。

### I1 CCV 成对反事实步级验证器（新增，押注）
- 动机：成功率先行；失败越早发现越值钱；POT verifier-only +17.5pp、Backtrack +7.4pp 证明验证/恢复有效。
- 差异：步级而非 episode 级；成对反事实训练而非只用户外结果标签；立体+本体+角色；单模型小头。
- 可行性：冻结 VLA 特征 + 小 MLP/Transformer；33k 演示 + NRB-2；8×H100 1–2 天。
- 资源：无新增真机数据；调试槽验证。
- 步骤：标签→特征缓存→成对训练→校准→阈值→接入 SLR。
- 风险：特征不含失败信息 → 加 stereo/proprio；OOD 过拟合 → 按场景 split；AUROC<0.7 → 回退几何谓词。

### I2 SLR 步级恢复原语（升级 SVL，押注）
- 动机：官方 human 备注是中途 undo；开环 chunk 不会自己发现/修复。
- 差异：从「终局 settle」扩展到 7 个原语；按失败步骤/角色选择；预算/安全壳。
- 可行性：恢复动作短、可脚本化；演示有自然重试；NRB-2 可造对。
- 资源：无新增数据；本地仿真/调试槽。
- 步骤：原语库→选择器→预算→与 CCV/SGG-2 接线。
- 风险：恢复反噬 → 先回安全位姿；误报 → 双阈值；长任务 → 限次数。

### I3 BRR 双臂角色路由（新增，押注）
- 动机：约 15 个双手任务；失败常在角色冲突/支撑手先松。
- 差异：显式 stabilize/manipulate/idle + 角色条件化；不是「双手一起动」。
- 可行性：演示自动标角色；小头；单 checkpoint；Dual-Level/SHS 证据。
- 资源：角色标签 + 5% 人工抽检。
- 步骤：标签→分类器→FiLM/AdaLN→迟滞→联合训练。
- 风险：标签噪声 → 二分类退化；切换振荡 → 迟滞；无增益 → 删。

### I4 SGG-2 步骤图/谓词（保留，降级）
- 动机：官方步骤/权重公开；提供步骤/相位/谓词标签。
- 差异：不再按步骤分分配预算；改为诊断 + CCV/SLR 标签。
- 可行性：确定性代码 + 小谓词头。
- 风险：谓词噪声；语言覆盖不全；用 160 复述 + embedding 兜底。

### I5 TCE torso 规范化/可选主动躯干（新增，可选）
- 动机：G1 有腰/高；API 暴露 lower_body/pivot；torso 系可稳定跨底座。
- 差异：默认只做 FK 规范化；主动躯干需调试槽标定，不赌。
- 可行性：数据集有 waist/state_torso；FK 可重建。
- 风险：pivot 语义未公开；主动运动可能触发安全/评分问题；默认关。

### I6 ACR 固定 chunk + RTC 边界混合（新增，工程必要）
- 动机：API 整段执行；chunk 固定；延迟/抖动影响可信度。
- 差异：不追求「每步闭环」；用相位速度曲线 + 边界混合。
- 可行性：纯工程；run_client 可压测。
- 风险：T_a 太大 → 晚发现；太小 → 延迟；用 benchmark 定。

### I7 NRB-2 官方备注恢复库（升级）
- 动机：human 备注是官方剧本；可直接造「破坏→恢复」对。
- 差异：从「自造扰动」升级为「忠实回放 + undo + 失败注入」。
- 可行性：1-DOF 刚体变换；2.5D 合成。
- 风险：备注编号含义未核实 → 同时覆盖通用扰动；合成域差 → 真实混采。

### I8 PCE 成对反事实实验协议（新增，方法论）
- 动机：320 trials 功效有限；不能靠 1–2pp 决策。
- 差异：预注册 + 配对 + 步隔离 + 失败注入 + A/B/A；把实验当一等公民。
- 可行性：流程/脚本；调试槽稀缺但可用。
- 风险：调试槽不可控 → 本地仿真相对比较；统计噪声 → 只报 +10pp 级。

### I9 PGL/OPT/ICR 终局子图（保留，降级）
- 动机：终局仍是成功闸门 39.8%；最后 3 厘米仍值钱。
- 差异：从主武器降为子图；只在「已到达终局」时启用。
- 可行性：第 7 轮已有设计。
- 风险：透明/布料失效 → 分桶回退；延迟 → 缓存。

### I10 GPR-VLA + WLA（保留）
- 动机：唯一学习主干；目标残差 + 可逆信念。
- 差异：接入 CCV/BRR/SLR 接口。
- 风险：底座微调不足 → LoRA 分级；单模型审计 → 头都在 checkpoint 内。

### I11 TLE/ACP/GF（保留，修剪）
- 动机：真实锚定反事实仍是最便宜的数据。
- 差异：本轮服务 CCV/SLR/BRR，不再全任务全物理。
- 风险：合成负迁移 → GF 软权重 + 真实混采。

### I12 DebugLoop/L2L/FLEET（支撑）
- DebugLoop：不计分单任务调试槽；每版本 1 槽；发布门。
- L2L：外部实验室数据；规则未明，默认 OFF。
- FLEET：N 端口、状态隔离、RTC、健康检查；工程检查单，不再当研究轴。

### I13 已砍清单
- 全 32 任务高保真孪生；自由仿真数据；运行时仿真/MPC；仿真 RL；布料/拉链/透明全物理；WMA-0 进主路径；每任务 LoRA/模型合并；「按任务切换 chunk」；「用步骤分加权补偿成功率」。
