## 1. 直觉：UniBot 的名字是一份"共享 + 隔离"的契约

**直觉 1（Uni = 共享，Bot = 个体）**：UniBot 的 "Uni" 要求一个模型覆盖 32 个任务，"Bot" 要求它在 N 台机器人上像 N 个独立个体一样工作。共享的是**不可变的能力**（权重、视觉/语言表征、技能先验），隔离的是**可变的经历**（观测历史、动作 chunk、检索先验、guard 状态机、进度头、随机数、延迟估计）。把两者混在一起，统一模型就会在并发评测中"串味"：A 端口的历史进入 B 端口的动作，或 A 的 reset 清掉 B 的缓冲。

**直觉 2（文档要求你负责，模板不替你负责）**：官方 README 把 state isolation 写成必须项（F21），但模板的 `PolicyService` 只隔离了 `_Channel`，所有连接共享同一个 policy 对象（F22）。这意味着：单端口本地 `run_client` 全绿，完全不能证明 N 端口并发评测不会互相污染。大多数队伍会在单端口上把模型调好，然后在评测时被一个不可见的共享变量、一个全局 RNG、一个 BatchNorm 批统计或一个全局 chunk 缓冲同时打掉多个 episode。

**直觉 3（状态隔离是"隐形地基"，不是"加分模块"）**：它本身不直接提高任何一个任务的步骤分，但它决定前两轮所有能力能否被**可复现地**兑现。I9 的检索先验、I4 的干预门控、I5 的进度头、I6 的共享 backend，全部是可变状态；没有状态契约，它们会从"模块"变成"泄漏源"。反过来，隔离做好后，I8 的离线-在线消融才可信：solo 与并发跑出的差异只来自被测变量，而不是状态串扰。

**三者统一**：前两轮造"能力"（数据引擎、泛化、消融），本轮造"容器"（状态契约、并发隔离、重置完备性）。**能力 × 容器 = 可复现的分数；能力 ÷ 容器 = 随机掉分。**

## 2. 严谨定义：从"清缓存"到"条件独立"

**定义 1（策略状态）**：策略 π 在时刻 t 的内部状态 s_t 是除当前观测 o_t 与不可变参数 W 之外、会影响输出 a_t 的全部变量。episode e 的状态记 s_t^e，其初态由 reset(e) 建立。

**定义 2（并发状态隔离）**：对任意两个 episode e ≠ e'（可并发、可同任务、可在不同端口），若

  π(a_t^e | o_{1:t}^e, s_0^e; W) = π(a_t^e | o_{1:t}^e, s_0^e, o_{1:t}^{e'}, a_{1:t-1}^{e'}; W)

对所有 t 成立，则称 π 满足并发状态隔离。即 e' 的观测/动作/状态不进入 e 的条件分布。

**定义 3（重置完备性）**：reset(e) 后 s_0^e = s*，其中 s* 是只依赖 W 与任务指令 d_e 的规范初态；并且对任意历史 h，reset 后的输出与"冷启动进程首次运行同一 episode"逐位一致（确定性）或在容差 ε 内同分布（随机性）。这比"清空缓存"更强：它要求**可复现**，而不只是"看起来重置了"。

**定义 4（任务状态隔离）**：在权重 W 冻结的推理期，任务 A 的 episode 状态（检索先验、进度头、校准/归一化统计、guard 状态）不改变任务 B 的条件输出分布：

  π(a^B | o^B, s^B; W, s^A) = π(a^B | o^B, s^B; W)。

训练期的任务干扰（负迁移）不在本定义内，仍由 I2 的采样/裁剪与 L0 消融负责。

**命题 1（统一策略的分解）**：若并发状态隔离成立，则对任意 episode 集合 E，联合动作分布因子化：

  p({a_t^e}_{e∈E} | {o_{1:t}^e}, W) = ∏_{e∈E} p(a_t^e | o_{1:t}^e, s_0^e; W)。

**证明思路**：对 |E| 归纳，用定义 2 逐个条件化，每一步都消去其他 episode 的变量，故联合分布等于边缘分布之积。**工程含义**：共享 backend 的正确性目标不是"让 N 个端口都能跑"，而是"让共享 backend 在分布上等价于 N 个互不通信的独立策略"。这给了我们一个可测试的等价性判据。

**定义 5（状态契约）**：每个可变状态必须声明五元组 (作用域, 可变性, 初态, 重置语义, 并发访问模式)。作用域 ∈ {全局只读, 端口, episode, 步}；跨 episode 共享的可变状态默认违规，除非能证明它不影响动作（例如只用于日志聚合）。表 1 是本方案的初始契约清单。

**表 1 · 状态契约清单（节选）**

| 组件 | 作用域 | 可变性 | reset 语义 | 并发模式 | 泄漏后果 |
|---|---|---|---|---|---|
| 模型权重 W / VLM / tokenizer | 全局 | 只读 | 不重置 | 共享只读 | 无 |
| FAISS 检索索引 | 全局 | 只读 | 不重置 | 并发读 | 无（搜索本身只读） |
| 量化/校准表 | 全局 | 只读 | 不重置 | 共享只读 | 若在线更新→违反"无在线学习"红线 |
| 观测/动作历史 | episode | 可变 | 清空 | 独占 | 串味→错误动作 |
| 动作 chunk 缓冲 | episode | 可变 | 清空 | 独占 | 返回陈旧 chunk |
| 检索先验 prior | episode | 可变 | 清空/重算 | 独占 | 错任务先验 |
| guard FSM（I4） | episode | 可变 | 回初态 | 独占 | 误判人手干预 |
| 进度头状态（I5） | episode | 可变 | 清零 | 独占 | 步骤分误判 |
| RNG（流匹配采样） | episode | 可变 | 按 episode 重播种 | 独占 | 非确定 + 跨 episode 相关 |
| 动作平滑/滤波状态 | episode | 可变 | 清空 | 独占 | 动作拖尾、跨端口耦合 |
| 延迟 EWMA / 自适应 chunk | episode 或全局只读 | 可变 | 重置 | 独占或原子读 | 一个端口的延迟改变另一个端口的节拍 |
| CUDA stream/workspace | 全局 | 可变但需可重入 | 不重置 | 每 episode 独立 stream 或串行化 | 数据竞争/非法内存 |
| BatchNorm running stats | 全局 | 训练期可变 | eval 只读 | 共享只读 | **train 模式下批统计跨 episode 泄漏** |
| 日志/指标聚合 | 全局 | 可变 | 不重置 | 加锁 | 只影响可观测性，不影响动作 |

**推论 1（三条最隐蔽的泄漏通道）**：(a) **批统计**——若共享 backend 把不同 episode 拼成一个 batch 且模型含 BatchNorm 或任何 per-batch 归一化，episode 之间通过 batch 统计耦合；解法是 eval 模式 + LayerNorm/GroupNorm，或禁止跨 episode 拼 batch。(b) **共享 RNG**——流匹配/扩散采样的随机数若来自全局 RNG，A 的采样步数会改变 B 的噪声序列；解法是 per-episode `Generator`，种子由 (task, first-obs hash) 确定性导出。(c) **错误缓存键**——检索先验/首帧嵌入若用 `task` 或 `last_obs` 作键而非 `(port, episode)`，会在同任务连续 episode 或不同端口间复用错误先验；解法是 context 键 = 端口 + episode 序号，reset 时整体替换。

## 3. 对第 2 轮痛点的增量修订

- P1/P2（能力/泛化）不变：本轮不改变"数据引擎是中期胜负手"的判断。
- **新增 P9（状态完整性）**：评测是 N 端口并发（F20/F21），单端口自测无法暴露跨 episode 泄漏；泄漏的代价是多个 episode 同时掉分，且难以归因。
- P6（部署预算）细化：Approach 2 共享 backend 是显存受限时的现实选择，但它把"状态隔离"从可选优化变成必答题（F21/F22）。
- P7（先手窗口）补充：状态隔离是低成本、低门槛、易被忽视的差异化项；先手做隔离测试套件，等于先拿到"可复现"这张底牌。
- P8（示教质量）不变。

## 4. 研究问题（本轮立项 Q9–Q10，Q1–Q8 保留）

- **Q9（并发隔离的可验证性）**：如何用可观测、可自动化的测试证明共享 backend 在分布上等价于 N 个独立策略？solo-vs-interleaved、canary 注入、reset 复现、batch 不变性、长时浸泡这五类测试的最小充分集是什么？泄漏度量如何与真机掉分对齐？
- **Q10（任务状态的隔离粒度）**：统一策略中哪些状态必须 episode/task 隔离（检索先验、进度头、RNG、平滑），哪些应全局共享（视觉/语言表征、技能先验、检索索引）？隔离粒度与泛化/吞吐的权衡边界在哪里？

## 5. 设计原则（新增 PR6/PR7，其余保留）

- **PR6 状态归属律**：任何可变状态必须声明作用域与重置语义；episode 作用域状态必须在 reset() 完全重建；跨 episode 共享可变状态默认违规。与 PR2 互补：PR2 管"一个模型"，PR6 管"模型之外的状态"。
- **PR7 无泄漏优先**：当隔离与吞吐/显存冲突时，先保隔离，再谈批处理；不能证明 batch 不变性的跨 episode 批处理一律关闭。
- PR1–PR5 保留（第 1/2 轮）。

## 7. 本轮最大风险

**一句话**：状态隔离是"不直接加分、但会一次性扣掉多个 episode"的隐形地基——如果只把它当成工程细节、不做 solo-vs-interleaved / batch 不变性 / reset 复现的自动化验证，那么一次跨端口的 RNG、BatchNorm 或缓存键泄漏就可能在 N 端口评测中同时污染多个 episode，而且官方模板只警告、不兜底；这是本轮方案最容易被低估、也最可能让前两轮能力集体失效的风险。

# UniBot-V1 参赛创新点清单（第 3 轮 v1.2）

> 检索日期：2026-11-26（第 1 轮）、2026-11-27（第 2/3 轮）；来源见 §5。承接 v1.1：I1–I9 维持/微调，新增 I10「状态隔离运行时」。清单只增改不重置。本轮主线：把评测单元从"一个模型"改写为"N 个并发的有状态策略实例"，用状态契约把前两轮的能力锁进可复现的容器。

## 0. 创新点清单

### I1 v2 考纲校准五轴增广引擎 ★★★★★（维持）
- **动机**：计分的 320 次真机评测每次都在 5 轴上偏离训练分布（P2/F2），泛化缺口是全局乘性损失。
- **做法**：32 张「考纲卡」（每任务 5 轴的具体扰动范围），增广参数从考纲卡分布采样，官方示例截图作锚点；每轴 3 档剂量（考纲内/边缘/外）做剂量-响应；位置×干扰物做 2 档交互。
- **差异**：直接 SFT 用标称数据；盲目增广用无校准随机化；本点把零样本泛化转成分布内泛化（PR1/PR5）。
- **资源/步骤**：1×24GB GPU；①32 张考纲卡 → ②背景/干扰物放量 → ③外观/位置 L0 先行 → ④定档 → ⑤交互验证。
- **风险**：考纲卡偏差（单任务通道抽测校准）；位置重拼接物理不可行（L0「不可行动作占比」>5% 降级为平移不变增广）。
- **本轮状态契约**：无新增可变状态。

### I2 v2 数据引擎 2.0：110 语料孪生迁移 + 加权共训 ★★★★★（维持）
- **动机**：单模型平均分被最弱任务支配（P1）；示教语料与质量双重浪费（P8）。
- **做法**：①按「技能孪生表」选择性入训 110 任务语料；②patch 官方 loader，实现族级权重（32 全量 + 孪生半权重 + 远任务 ≤5%），因官方配置 weight 不生效（F11）；③按进度效率/平滑度/成功裕度做 per-episode 质量加权，剪最差 10%。
- **差异**：均匀混训把容量浪费在已会任务与低质示教；本点诊断先行、孪生定向、权重受控。
- **资源/步骤**：孪生子集 ≈1–2TB + 32 任务 ≈2TB；1×24GB 起步、8×A100 上限；①孪生表 → ②下载子集 → ③loader patch + 单测 → ④首轮共训 → ⑤族级 L0 验证后放量。
- **风险**：负迁移（孪生任务动态相反）；相机配置不一致。**训练期任务隔离**仍由本点的采样/裁剪与 L0 消融负责，推理期任务隔离交给 I10。

### I3 接触任务族关键点视觉伺服回退 ★★★★（维持）
- **做法**：通用 chunk 策略负责接近段、几何伺服负责接触段，同一策略服务内混合推理（PR2 边界待确认，最大前提）；`ee` 控制空间 + per-step 调用天然支持；开放词汇检测零训练起步；触发滞回 + 低置信回退。
- **降级预案 I3'**：若组委会裁定混合推理违规，改为「训练时辅助监督」，推理纯端到端。
- **本轮状态契约**：伺服的关键点缓存、滞回计数器全部移入 `EpisodeContext`，禁止放全局。

### I4 人手干预感知门控 + 自适应 chunk ★★★★（微调）
- **做法**：手部检测 + `obs_delta_indices` 历史栈判别干预（<50ms）；状态机 INTERFERED→停持→重估→续做（PR3）；干预态短 chunk（4–6 步）、稳定态长 chunk（8–16 步，参照 15Hz/horizon 16，F12）。
- **本轮状态契约**：`GuardFSM`、延迟 EWMA、当前 chunk 长度均为 episode 状态；一个端口的延迟不得改变另一个端口的 chunk 节拍。

### I5 v2 非标称示教合成 + 得分点对齐恢复 ★★★★（微调）
- **做法**：①扰动重放（中间态注入物体位姿/抓取点扰动）；②跨段缝合（A 接近 + B 抓取）；③WMA-0 仿真续写（缓）；④官方得分点做里程碑检测器，只有达成下一得分点的合成段才保留。
- **差异**：恢复行为来自数据分布内，而非手工恢复原语；进度头监督从自造里程碑改为官方得分点。
- **资源/步骤**：1×24GB；2 人周数据工程；①得分点逆向 → ②3 个弱任务试点（PlugCharger/ZipUp/PourOutMedicine）→ ③进度头改监督 → ④LoRA 增量 → ⑤单任务 A/B。
- **风险**：合成偏离分布失配；检测器误差污染标签。
- **本轮状态契约**：进度头状态 per-episode，reset 清零。

### I6 v2 确定性低延迟部署服务 ★★★★（升级）
- **做法**：共享 backend + 每端口独立队列；fp8/INT8 量化、torch.compile/CUDA Graph、obs 预取、`image_resize` 压带宽、断线重连 + 健康探针（PR4）。
- **本轮升级（状态隔离）**：显式支持官方 README 的 **Approach 2**（N 个轻量 websocket 端点 → 一个共享推理 backend），但把并发与状态隔离作为硬约束交给 I10：模型 forward 必须是无全局可变状态的纯函数，所有 episode 状态由 `EpisodeContext` 持有；异步 handler 必须把同步/GPU 计算移出事件循环（F22）。
- **资源**：官方 frozen-VLM 单卡可跑（F11）→ 2×A100 80G 共享 backend 覆盖 N=3–5 端口；单步预算参照 15Hz（≈66ms），目标 p99 <40ms，并发/单路 p99 比 <1.2。

### I7 世界模型测试时前瞻 ★★（缓）（维持）
- **做法**：高险节点 O(1–2) 次小规模 rollout 择优；第 3 轮基线延迟余量不足即裁撤推理路径；WMA-0 资产转 I5 数据引擎。
- **本轮状态契约**：rollout 的隐状态、缓存帧、随机种子必须 episode 隔离；不得把一次 rollout 的结果缓存给下一 episode。

### I8 v3 评测运营闭环 + 分级消融注册表 ★★★★（升级）
- **做法**：L0 in-silico 消融（考纲轴偏移，代理指标 Δprog/Δact/Δkp）→ L1 分数因子设计 → L2 真机 top 2–3；注册表滚动计算「离线预测 vs 真机增益」的 Spearman，相关性 >0.6 才可单独准入 L2。
- **本轮升级**：**隔离测试是所有 A/B 的前置门禁**。solo 与并发结果不一致时，先修状态泄漏，再谈模块增益；否则注册表记录的是串扰，不是因果效应。
- **风险**：离线代理与真机相关建立慢（用 3–4 个已知真机结果回填）。

### I9 reset 期检索类比迁移 ★★★★（微调）
- **做法**：`reset()`（每 episode 一次，F18）用 VLM/DINOv2 嵌入把首帧目标物体映射到「物体-技能库」（110 语料 + 32 任务首帧离线构建），检索结果作为 episode 全程的动作先验；零权重更新。
- **差异**：未见物品轴的零样本 = 检索后类比，而非纯参数化平均。
- **资源/步骤**：嵌入 1×GPU 日 + FAISS；①物体库 → ②嵌入索引 → ③动作先验参数化 → ④reset 检索 + 软注入 → ⑤未见轴 L0 + 真机抽测。
- **本轮状态契约**：检索索引全局只读；`prior` 必须 episode 作用域，键为 `(port, episode_id)`；距离阈值门控，超阈退回无先验。

### I10 状态隔离运行时（新） ★★★★★
- **动机**：评测是 N 端口并发（F20/F21），官方模板只隔离连接、不隔离策略状态（F22）；单端口自测无法暴露跨 episode 泄漏。共享 backend 是显存受限时的现实选择，但它把状态隔离从"可选优化"变成"必答题"。
- **与现有方案差异**：多数队伍用 Approach 1（N 份模型）或只做单端口调试；本点不把隔离当成"记得清缓存"，而是形式化为**状态契约 + 五类自动化测试 + 泄漏度量门禁**，并给出"共享 backend 分布等价于 N 个独立策略"的可测试判据（命题 1）。
- **技术可行性**：高。核心重构是 `EpisodeContext` + 无状态共享 forward + per-episode RNG/stream/lock；N 个轻量端点复用官方 websocket/msgpack 传输（F12/F21）。不需要新模型，不触碰 PR2 单模型边界。
- **所需资源**：1 人周工程 + 1 人周测试；无额外 GPU（隔离测试可在单卡/CPU stub 上跑）；共享 backend 反而节省 N 份显存。
- **落地步骤**：①按表 1 做状态清单与作用域审计（全局搜索可变单例/模块级变量）；②引入 `EpisodeContext`，把 I4/I5/I9 的状态全部迁入；③实现五类隔离测试（solo-vs-interleaved、canary 注入、reset 复现、batch 不变性、长时浸泡）；④把隔离测试接入 PR6 门禁与 CI；⑤N ∈ {1,3,5,8} 并发压测（p99、动作规整性、显存/内存）；⑥真机单任务通道抽测，对照 solo 结果。
- **风险**：过度串行化导致吞吐下降（缓解：同一 episode 串行、不同 episode 并行；只对无状态视觉编码做跨 episode batch，且必须过 batch 不变性测试）；跨 episode 批处理与隔离冲突（缓解：PR7，不能证明不变性就关闭）；官方 N 与并发调度未知（缓解：按 N=8 上限设计，按 N=3 验收）。

### 1.1 状态契约与 EpisodeContext（I10）

```python
import threading
import numpy as np
from dataclasses import dataclass, field

@dataclass
class EpisodeContext:
    port: int
    episode_id: int
    task: str
    rng: np.random.Generator                 # per-episode，禁止全局 RNG
    obs_hist: list = field(default_factory=list)
    action_chunk: np.ndarray | None = None
    prior: object | None = None              # I9 检索先验
    guard: object = None                     # I4 FSM
    progress: object = None                  # I5 进度头
    lat_ewma: float = 0.0                    # I4 自适应 chunk
    lock: threading.Lock = field(default_factory=threading.Lock)

    @classmethod
    def canonical(cls, port, episode_id, task, seed):
        return cls(port=port, episode_id=episode_id, task=task,
                   rng=np.random.default_rng(seed),
                   guard=GuardFSM.new(),
                   progress=ProgressState.zero(),
                   lat_ewma=0.0)

class UniBotRuntime:
    """W / index 全局只读；所有可变状态都在 EpisodeContext。"""
    def __init__(self, model, index):
        self.model = model.eval()            # 禁止 train 模式 BN（推论 1a）
        self.index = index                   # FAISS 只读，可并发 search
        self.ctx: dict[tuple[int, int], EpisodeContext] = {}
        self._ctx_lock = threading.Lock()

    def reset(self, port, episode_id, task, first_obs=None):
        seed = stable_seed(task, first_obs)  # 由任务+首帧哈希导出，可复现
        c = EpisodeContext.canonical(port, episode_id, task, seed)
        if first_obs is not None:
            c.prior = self.retrieve(first_obs, task)   # 只读索引，结果入 ctx
        with self._ctx_lock:
            self.ctx[(port, episode_id)] = c           # 按端口替换，天然有界
        return c

    def get_action(self, port, episode_id, obs):
        c = self.ctx[(port, episode_id)]
        with c.lock:                          # 同 episode 串行，不同 episode 并行
            a = self.model(obs, c)            # forward 不写任何全局可变状态
            c.action_chunk = a
            return a
```

### 1.2 隔离式共享 backend（I6 + I10）

```python
import asyncio

async def handle(port, ws):
    async for frame in ws:
        req = thaw(frame)
        if req["type"] == "policy_reset":
            runtime.reset(port, req["episode_id"], req["task"],
                          req.get("first_obs"))
            await ws.send(freeze({"ok": True}))
        else:
            # 关键：同步/GPU 计算移出事件循环，避免一个端口阻塞全部端口（F22）
            a = await asyncio.to_thread(
                runtime.get_action, port, req["episode_id"], req["obs"])
            await ws.send(freeze(a))
```

> 生产实现用专用推理 worker + per-episode CUDA stream；`asyncio.to_thread` 只是最小可行示意。跨 episode 拼 batch 仅允许用于无状态视觉编码，且必须先通过 1.3 的 batch 不变性测试。

### 1.3 五类隔离测试（I10）

```python
def assert_isolation(runtime, epA, epB, tol=1e-6):
    # 1) solo vs interleaved：A 单独跑 与 A/B 交错跑，动作必须一致
    runtime.reset(*epA.meta); a_solo = run_episode(runtime, epA)
    runtime.reset(*epA.meta); runtime.reset(*epB.meta)
    a_inter = run_interleaved(runtime, epA, epB)
    assert max_abs(a_solo, a_inter) <= tol, "interleaving changed A"

    # 2) canary 注入：B 跑极端观测，不得改变 A
    runtime.reset(*epA.meta); runtime.reset(*epB.meta)
    run_episode(runtime, epB, poison=True)
    a_after = run_episode(runtime, epA)
    assert max_abs(a_solo, a_after) <= tol, "B poisoned A"

    # 3) reset 完备性：同一 episode 重置后逐位复现
    runtime.reset(*epA.meta); a1 = run_episode(runtime, epA)
    runtime.reset(*epA.meta); a2 = run_episode(runtime, epA)
    assert bitwise_equal(a1, a2), "reset not complete"

    # 4) batch 不变性：批跑 vs 单跑一致（抓 BN / per-batch 归一化泄漏）
    assert batch_invariance(runtime, [epA, epB], tol)

    # 5) 长时浸泡：上下文有界、内存不增长、无残留全局状态
    assert soak(runtime, episodes=200, max_rss_growth_mb=50)
```

### 1.4 泄漏度量与 PR6 门禁（I8 + I10）

```python
L_act   = max_t || a_t^solo - a_t^interleaved ||_inf      # 动作泄漏
L_state = |{ f : hash(s_f^A | s^B) != hash(s_f^A) }|      # 状态泄漏字段数
R_defect = int(not bitwise_equal(a_after_reset, a_cold_start))  # 重置缺陷
C_lat   = p99_concurrent / p99_solo                       # 延迟耦合
G_mem   = ΔRSS per 100 episodes                           # 内存增长

PR6_GATE = (L_act == 0 and L_state == 0 and R_defect == 0
            and C_lat < 1.2 and G_mem < 50)
```

> 随机性模块（流匹配/扩散）用 per-episode 固定种子，使 `L_act` 仍可要求逐位为 0；若必须比较分布，则改用固定样本的 TV/Wasserstein 距离，阈值单列。

## 2. 实验设计（分级消融协议 v3）

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0-iso | 五类隔离测试；N ∈ {1,3,5,8} 并发压测；solo vs 并发动作/延迟对照 | 本地 stub（免费） | L_act=0、L_state=0、R_defect=0、C_lat<1.2、G_mem<50MB |
| L0-model | I1 各轴剂量-响应；I2 孪生家族正/负迁移；I9 先验不伤标称；I5 合成示教质量 | 离线（免费） | 孪生：Δprog>0 且无家族退步；I9：标称 Δprog≥0 且未见轴 Δprog>0 |
| L1 | 2^(k-p)：增广 4 轴 × {on/off}；guard 栈 3 模块析因 | 离线 + 少量真机 | 主效应显著的 ≤3 个组合进入 L2 |
| L2 | top 组合真机确认：≥2 任务 × 各 2 次/任务 | 单任务通道 | 真机增益 ≥ 离线预测的 50%；且 solo/并发差异不显著 |
| 门禁 | PR4 延迟/动作健康度 + PR6 状态契约 | 本地 N 端口 stub | 0 拒绝动作、p99<40ms、C_lat<1.2、无 NaN/离群 |

**首批 L2 排队计划**：①I10 隔离门禁 + I2 共训基线（32 任务诊断矩阵）→ ②I1 背景+干扰物轴 → ③I5 试点 3 任务 → ④I9 未见轴抽测。**顺序变化**：I10 从"部署阶段再做"提前到"任何真机 A/B 之前"，因为它是实验可信度的前置条件。

## 6. 本轮最值得押注（一句话）

## 7. 本轮最大风险

**一句话**：I10 的收益是"避免掉分"而非"直接加分"，若团队因它不产生可见步骤分而跳过自动化隔离验证，一次跨端口状态泄漏就会在 N 端口评测中同时污染多个 episode，且官方模板只警告不兜底——这是本轮方案最容易被低估、也最可能让前两轮能力集体失效的风险。
