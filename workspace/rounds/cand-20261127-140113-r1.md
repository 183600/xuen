## 1. 直觉与动机

### 灵感 1（文化适应性 → 目标不是从像素里长出来的，是「习俗」规定的）

直觉：桌面任务的难点是分层的——「怎么动」是技能问题，「动到哪、摆成什么样」是目标问题。32 任务里大量是 arrangement/storage/packing（ArrangePlates、OrganizeBookshelf、OrganizePencilCase、OrganizeStationery、ToolboxStorage、StoreCups、PackBag、PackDoll、StoreEarphones、StorePaddle、PickOutBatteries…）。它们的成功与步骤分取决于一个**未被指令完全说清的目标构型**：盘子怎么排、书怎么立、什么放哪个格子。这个目标构型是功能/习俗约定（杯子进杯架、电池进电池盒、书脊朝外、同类同处），不是从训练帧里唯一可辨识的。大多数队伍把它留给端到端 VLA 隐式记忆，于是在新布局/未见物体下退化成「把东西挪来挪去」。文化适应性的可操作化：把「当地习俗」显式化——**静态功能先验**（物体类别 → 容器/位置类型）+ **场景指代消解**（当前场景里哪个容器承担这个角色）+ **现有摆放类比**（同类物体已在哪，新物体跟着去哪）。核心反直觉点：**目标态是推理出来的，不是回归出来的；先想清楚「摆成什么样」，再让 VLA 去执行。**

### 灵感 2（技能组合 → 长程任务是技能的排列组合，不是帧的回归）

直觉：32 任务不是 32 个独立函数，而是约 10 个技能原语（reach/grasp/lift/transport/place/insert/pour/open/fold/zip）在不同物体、容器、顺序上的组合。端到端逐帧回归把「组合结构」浪费掉了：每个任务从零学同样的抓取；长程任务无法复用；错误无法在技能边界重规划。技能组合视角的三件事：(a) **分词**——用夹爪开合、速度极小值、视觉变化点把示教切成技能段，聚类成技能词表；(b) **组合**——跨任务/跨示教拼接技能段，合成反事实长程示教（A 的抓 + B 的放），用 I5 得分点检测器过滤；(c) **条件执行**——目标场景图 → 技能计划 → 同一 VLA 按子目标逐步执行，技能边界即重规划/恢复点。核心反直觉点：**数据量已经不是瓶颈，数据的「可组合粒度」才是；把示教切成技能，等于把 32k 条示教变成可重组的技能语料库。**

### 两者统一

文化适应性回答「目标态是什么」（目标结构），技能组合回答「如何把目标拆成可复用动作」（技能结构）。前者给后者提供子目标序列，后者给前者提供可执行性与进度反馈。与上一轮「数据引擎」结论的关系：数据引擎解决「数据从哪来、权重怎么给」，本轮解决「数据以什么结构进入模型」——**从数据引擎升级为结构引擎**。这也直接服务单模型约束：结构在训练期蒸馏进同一个 VLA，推理期最多多一次轻量规划/一次前向，不引入第二个任务模型。

## 1.1 严谨定义（把直觉变成可消融的对象）

- **目标结构**：\(G=(O,R,\Pi)\)。\(O\) 为场景物体与容器；\(R\) 为目标关系集合（object–receptacle、object–pose、order/grouping）；\(\Pi\) 为子目标的偏序。若指令 + 初始场景不能唯一确定 \(R\)，称该任务**目标欠定**。文化适应性 = 在零权重更新下，用功能先验 + 场景证据推断 \(R\) 并适配到新约定的能力。
- **技能结构**：示教轨迹的一个分段 \(S=\{(s_i,\ell_i,\mathrm{pre}_i,\mathrm{post}_i)\}\)，\(\ell_i\in\mathcal{V}\) 为技能词表中的标签，pre/post 为物体/夹爪/末端状态条件；组合算子 \(\circ\) 仅在兼容谓词 \(\mathrm{compat}(\mathrm{post}_i,\mathrm{pre}_j)\) 与语义谓词成立时定义。
- **结构杠杆**：\(\Delta_{\text{score}}/\Delta_{\text{compute}}\)。本轮只保留能用 L0 离线代理指标测出正增益的结构改动；测不出的退回纯数据增广。

## 2. 对上一轮痛点的增量修订

- P1–P8 保留。
- 新增 **P9（目标欠定）**：arrangement/storage/packing 类任务的目标构型由功能/习俗约定决定，指令只给部分信息；端到端策略易记忆单一布局，在新布局/未见物体上步骤分流失。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I1 v3 考纲校准增广引擎 ★★★★★
- **动机**：沿用 v1.1；本轮新增 P9——目标欠定不仅靠「看到什么」，也靠「摆成什么样」；增广应覆盖储物约定与布局，而不只是像素。
- **本轮深化**：新增「布局/约定增广」轴：同一任务采样不同容器类型/位置/已有摆放（例如杯架 vs 杯柜、书按大小 vs 按颜色），生成「同任务、不同习俗」的训练对；像素类轴（背景/光照/干扰等）降为基线，预算转向布局轴。
- **与现有方案差异**：盲目像素增广不改变目标语义；本点让训练分布覆盖「约定变化」，与 I10 的目标先验互补。
- **技术可行性**：中-高。布局增广可用分割 + inpainting/物体重摆放；或直接用 I11 技能重组生成不同布局的示教。
- **资源**：1×24GB GPU；布局增广与 I11 共用数据管线。
- **落地**：①32 任务布局轴定义（容器/位置/顺序）；②每任务 3 档约定（原约定/邻近约定/远约定）；③L0 剂量-响应；④与 I10-L1 联合消融。
- **风险**：布局增广物理不可行（缓解：碰撞/可达性检查）；约定轴与真实评测不符（缓解：只用弱约束，L2 抽测校准）。

### I2 v3 数据引擎 2.0：孪生迁移 + 质量/风格加权 ★★★★★
- **动机**：沿用 v1.1；新增 P10——多遥操作者示范风格混杂，均匀 SFT 会平均掉不兼容风格。
- **本轮深化**：
  1. **孪生语料入训**（保留）：110 语料按技能孪生表选择性入训。
  2. **loader 加权 patch**（保留）：32 考题全量 + 孪生半权重 + 远任务 ≤5%。
  3. **质量 + 风格加权**（升级）：质量分 = 进度效率 × 平滑度 × 成功裕度；风格分 = 对速度/接近方向/停顿模式聚类后的「风格纯度」；per-episode 权重 = 质量 × 风格，避免把两种风格平均进同一个动作分布。推理时固定使用验证集上最优的风格簇（或风格 token）。
- **与现有方案差异**：不是简单剪最差 10%，而是识别「风格不可兼容」导致的模式平均。
- **技术可行性**：高（聚类 + 加权采样，单卡可跑）。
- **资源**：孪生子集 ≈1–2TB + 32 任务 ≈2TB；1×24GB 起步、8×A100 上限。
- **落地**：①风格特征（速度/接近方向/停顿时长）聚类；②权重单元测试（batch 内风格分布）；③首轮共训；④族级 L0 消融。
- **风险**：风格聚类把任务差异误当风格（缓解：按任务分层聚类）；负迁移（缓解：家族级 L0、低权重起步、退步即裁剪）。

  3. **技能完成检测器**（升级）：由得分点里程碑检测器扩展为「技能 post 条件是否达成」的轻量分类器（物体是否在容器内、夹爪是否闭合、物体是否直立），用于组合样本的自动门禁。
  4. **世界模型生成**（保留但降级）：WMA-0 仿真模式仅作数据引擎，不再用于测试时前瞻（I7 裁撤）。
- **与现有方案差异**：v2 的恢复行为来自同任务数据分布；v3 的组合行为来自跨任务技能分布，直接训练组合泛化。
- **技术可行性**：中-高。分段/拼接是数据工程；检测器是轻量视觉分类器。
- **资源**：1×24GB GPU；数据工程 2–3 人周；检测器 1 GPU 日/技能族。
- **落地**：①技能分词（I11）；②3 个任务试点（OrganizePencilCase/StoreCups/PlugCharger）；③组合样本物理/语义过滤；④LoRA 增量训练；⑤L0 + 单任务通道 A/B。
- **风险**：组合样本分布外（缓解：3 帧平滑、低权重、L0 验证）；检测器误差污染标签（缓解：置信门控 + 5% 人工抽检）；语义不兼容（缓解：I10 schema 的 object–receptacle 兼容表）。

### I6 确定性低延迟部署服务 ★★★★（维持）
- 六要素同 v1.1。本轮补充：**规划一次、执行多步**——I10 目标规划与 I9 检索只在 reset/首帧做一次并缓存（<50ms，CPU 可承担）；episode 内技能条件只改 prompt，不增加前向次数；p99 目标维持 <40ms（15Hz 参照，F12）。若启用 I10-L2 感知，必须离线蒸馏或放在 reset 期，禁止每步调用检测器。

### I7 世界模型测试时前瞻 ✂（本轮修剪）
- **决定**：裁撤推理路径。理由：I10/I11 已用更低成本提供目标/技能结构；世界模型每步 rollout 与 66ms 预算冲突，且 L0 代理指标难以证明其边际收益。
- **资产去向**：WMA-0 仿真模式并入 I5 v3 的组合样本生成；DynamiCrafter 视频先验用于技能段之间的过渡帧补全。裁撤不等于废弃。

### I8 v3 评测运营闭环 + 分级消融注册表 ★★★★
- **动机**：沿用 v1.1；新增结构消融与结构诊断指标。
- **本轮深化**：
  - **L0 结构消融**：目标先验 on/off（I10-L1）、技能条件 on/off（I11）、组合样本比例 r∈{0,10,20,30}%、leave-one-skill-out、I2 风格加权 on/off。
  - **结构诊断指标**（新增，替代单一 Δprog）：①目标关系准确率（终态是否满足 schema 的 R）；②技能边界 F1（对人工标注小子集）；③组合有效率（物理/语义/完成检测器三重通过率）；④leave-one-skill-out 迁移增益。
  - **L1 分数因子**：{目标先验, 技能条件, 组合数据, 风格加权} 四因子 2^(4-p) 部分析因，主效应优先。
  - **L2 真机**：只测 L0+L1 联合排名 top 2–3；每候选 ≥2 任务 × 各 2 次，至少含 1 个 arrangement + 1 个 insertion。
  - **注册表**：记录「离线结构指标 vs 真机步骤分增益」，滚动 Spearman；某指标 >0.6 才可单独准入 L2。
- **技术可行性**：高（L0 纯离线）。
- **资源**：指标实现 1–2 人周；注册表 = 表格 + 脚本。
- **落地**：①结构诊断指标；②注册表 schema；③首个用例 = I11 技能组合；④每月复盘。
- **风险**：离线结构指标与真机步骤分脱节（缓解：先用已知真机结果回填 3–4 个对齐点；指标不达标只作参考，不替代 L2）。

### I9 v2 两级检索类比迁移 ★★★★
- **动机**：沿用 v1.1；本轮把检索拆成目标级与动作级，与 I10 共享 reset 期一次感知。
- **本轮深化**：
  - **目标级检索**：从 32 任务/110 语料的「目标 schema 库」检索当前指令对应的 \(G=(O,R,\Pi)\)（容器类型、目标关系、子目标顺序）。
  - **动作级检索**：用 DINOv2/VLM 嵌入把首帧目标物体映射到最近邻示教的关键动作参数（夹爪开度、接近高度/朝向、技能模式）。
  - **共享一次感知**：reset/首帧做一次检测 + 嵌入，目标级与动作级共用；episode 内缓存，零额外每步开销。
  - **止损**：距离阈值门控；目标级先验只作软偏置（写进 prompt），超阈退回原始指令。
- **技术可行性**：中-高。嵌入库一次性离线构建；reset 期 <1s。
- **资源**：嵌入 1×GPU 日 + FAISS；1 人周。
- **落地**：①目标 schema 库 + 物体-技能库；②嵌入/索引；③两级检索与缓存；④L0 未见轴 + 新约定测试；⑤真机抽测。
- **风险**：误检索注入错误先验（缓解：软偏置 + 阈值 + L0 不伤标称）；目标级 schema 与场景不符（缓解：只用弱约束，场景指代兜底）；合规性书面确认。

### I10 场景习俗目标先验（新） ★★★★
- **动机**：P9——arrangement/storage/packing 类任务的目标构型由功能/习俗约定决定，指令欠定；端到端 VLA 隐式记忆单一布局。
- **与现有方案差异**：端到端把目标留在权重里；本点把目标态变成可读、可消融、可复用的结构，并通过语言通道注入，不破坏单模型。
- **三层实现（风险递增）**：
  - **L1 语言注入（默认，零额外推理）**：离线构建 32 任务目标 schema（物体类别、容器类型、目标关系、软顺序、里程碑）；训练时把原始 instruction 扩写为「原始指令 + Goal: … + Order: …」，推理时同样扩写并缓存；同一 VLA 一次前向。
  - **L2 场景指代（可选）**：reset/首帧用开放词汇检测/分割把 schema 的容器类型 ground 到当前场景的具体容器，把指代写进子目标文本（「put the cup into the cup rack on the left」）；感知可离线蒸馏进 VLA，推理期可关闭。
  - **L3 目标图 + 技能计划（研究上限）**：显式 goal scene graph + 技能计划，逐步条件执行与进度监控；仅在 L0 证明增益且合规确认后启用。
- **技术可行性**：L1 高（纯文本 + 数据重标注）；L2 中（检测/分割 + 指代）；L3 中（场景图 + 规划）。
- **资源**：L1 1 人周 + LLM 标注；L2 1×GPU 离线伪标 + 1 人周；L3 另计。
- **落地**：①32 任务 schema 表；②标记目标欠定家族（预计 8–12 个）；③训练 instruction 扩写；④LoRA 对比（原始 vs 扩写）；⑤L0 结构消融；⑥L2/L3 按增益决定。
- **风险**：schema 与真实约定不符（缓解：只用弱约束「同类同处/容器功能」，不硬编码唯一布局）；扩写文本过长/分布外（缓解：多模板、长度控制、保留原始指令）；感知模块被裁定为第二模型（缓解：L1 默认、L2 离线蒸馏、合规确认）。

### I11 技能分词与组合数据引擎（新） ★★★★★
- **动机**：P10/P11——长程任务是技能组合，逐帧/整段训练不建模技能边界，跨任务复用与组合泛化弱。
- **与现有方案差异**：不是加一个新网络，而是把「技能」作为**数据与条件的结构**：离线分词 → 技能词表 → 组合样本 → 技能条件训练；推理期仍是一个 VLA。
- **三件事**：
  1. **技能分词**：边界 = 夹爪开合跳变 + 末端速度局部极小 + 视觉变化点；聚类成技能词表（reach/grasp/lift/transport/place/insert/pour/open/fold/zip）；每段记录 pre/post 条件。
  2. **技能组合**：跨任务/跨示教拼接（A 的 grasp + B 的 place），用兼容谓词 + 物理检查 + I5 技能完成检测器过滤；生成反事实长程示教。
  3. **技能条件训练/执行**：训练时在 instruction 前加 `[SKILL:…][OBJ:…][REC:…]` 前缀或加辅助技能头；推理时目标 schema → 技能计划 → 按子目标逐步执行；技能边界 = 重规划/恢复点。
- **技术可行性**：中-高。分词/聚类/拼接是数据工程；技能条件可用前缀 token，不新增网络。
- **资源**：1×24GB GPU；数据工程 2–3 人周；技能词表人工抽检。
- **落地**：①3 个任务分词试点；②技能词表 K 选择（轮廓系数/重构误差）；③组合样本过滤与混采比例；④LoRA 技能条件训练；⑤L0 + 真机 A/B；⑥放量到 32 任务。
- **风险**：边界估计噪声（缓解：多信号投票 + 人工抽检 + 技能完成检测器兜底）；组合样本物理/语义无效（缓解：兼容谓词 + 物理检查 + 低权重）；技能词表过细导致数据碎片化（缓解：K 上限 + 短段合并）；单模型边界（前缀 token/辅助头属同一模型，需确认）。

def ground_receptacle(first_obs, schema, target_obj):
    det = open_vocab_detect(first_obs, schema["receptacle_types"])  # 4 相机
    if not det:
        return None
    # 打分：类型匹配 + 已含同类物体 + 距目标物体近 + 可见性
    return max(det, key=lambda r: type_match(r, schema)
                                   + 0.5 * has_same_class(r)
                                   - 0.2 * dist(r, target_obj))

def segment_episode(ep):
    bounds = [0]
    for t in range(1, len(ep)):
        if (gripper_changed(ep, t) or
            is_motion_pause(ep, t, v_eps=0.01) or
            visual_change(ep, t) > tau_vis):
            bounds.append(t)
    bounds.append(len(ep))

    segs = []
    for a, b in zip(bounds[:-1], bounds[1:]):
        seg = ep[a:b]
        seg.skill = skill_cluster.predict(features(seg))  # reach/grasp/lift/transport/place/insert/pour/open/fold/zip
        seg.pre  = (obj_pose(seg, 0),  gripper(seg, 0))
        seg.post = (obj_pose(seg, -1), gripper(seg, -1))
        segs.append(seg)
    return merge_short(segs)   # 合并 <3 帧碎片

### 1.4 技能组合与过滤（I5 v3 / I11）

```python
def recombine(segA, segB, schema):
    if segA.skill not in {"reach", "grasp", "lift"}:
        return None
    if segB.skill not in {"transport", "place", "insert"}:
        return None
    if not compatible(segA.post, segB.pre):          # 物体/容器/夹爪状态
        return None
    if not semantic_ok(schema, segA.obj, segB.rec):  # object-receptacle 兼容
        return None
    traj = stitch(segA, segB, blend=3)                # 3 帧平滑过渡
    if not physics_ok(traj):                          # 关节限位/速度/碰撞代理
        return None
    return traj

# 质量门禁：I5 技能完成检测器 + 语义兼容 + 物理可行
# 混采：组合样本占比 r ∈ {0, .1, .2, .3}，低权重起步；L0 验证后再放量
```

### 1.5 技能条件执行（I11）

```python
class StructuredPolicy:
    def reset(self):
        self._ready = False
        self._cache = None

    def _prepare(self, first_obs):
        # 目标级（I9 v2 / I10）+ 动作级（I9 v2）共享一次感知
        self.goal  = infer_goal(first_obs, self.lang, GOAL_SCHEMA)   # L1: 仅语言 schema
        self.prior = retrieve_action_prior(first_obs, self.lang)      # I9 v2
        self.plan  = self.goal.to_skill_plan()                        # [("pick", cup), ("place", cup, rack), ...]
        self.k = 0
        self._ready = True

    def get_action(self, obs):
        if not self._ready:
            self._prepare(obs)
        if self.k < len(self.plan):
            sg = self.plan[self.k]
            prompt = (f"[SKILL:{sg.skill}] [OBJ:{sg.obj}] [REC:{sg.rec}] "
                      f"{self.goal.text}")
        else:
            prompt = self.goal.text
        chunk = self.vla.propose_chunk(obs, prompt=prompt, prior=self.prior)
        if self.skill_done(obs, sg):     # 技能边界 = 重规划/恢复点
            self.k += 1
        return self.guard_stack(chunk, obs)   # I3/I4/I5 guard 不变
```

## 2. 实验设计（结构消融协议 v3）

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0 | I10-L1 目标扩写 on/off；I11 技能条件 on/off；组合比例 0/10/20/30%；leave-one-skill-out；I2 风格加权 on/off | 离线（免费） | 目标欠定家族 Δprog>0 且非 arrangement 不回归；组合有效率 > 阈值；leave-one-skill-out 迁移 > 0 |

| L2 | top 组合真机确认：≥2 任务 × 各 2 次，至少 1 个 arrangement + 1 个 insertion | 单任务通道 | 真机增益 ≥ 离线预测的 50% |

## 6. 本轮最值得押注（一句话）

**押「结构引擎」：I11（技能分词 + 组合数据）× I10-L1（目标态语言注入）——两者都不改推理架构、不碰单模型红线，却把 32k 条示教从「整段轨迹」变成「可重组的技能语料 + 可读的目标规格」；在 arrangement/storage/packing 家族上，这比再加像素增广更可能直接换来步骤分。**

## 7. 本轮最大风险（一句话，结尾）

**最大风险是结构假设本身错误——目标欠定可能没有想象中严重、场景图/技能边界误差可能把噪声注入训练与推理，而 I10 感知模块还可能被裁定为「第二个模型」；因此默认只走 I11 + I5 v3 的数据侧结构化与 I10-L1 语言注入，任何推理期结构模块必须先过 L0 增益与合规双闸再放量。**
