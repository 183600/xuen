## 1. 直觉（先给画面，再给定义）

**灵感 1（记忆检索：模型把 32k 示教压成了权重，却失去了「查得到」的能力）**
- 人类抓一个没见过的杯子，不会从零学抓取，而是回忆「像它这样的杯子上次怎么抓」。RAG 在语言模型上已经说明：参数记忆与非参数记忆互补。VLA 只有参数记忆——32k eps 被压进 DiT 权重，**具体的成功片段不可寻址**。于是同一场景下模型可能采样到次优模式，而训练集里明明存在更好的片段。检索把「训练集」重新变成推理时可查询的先验，且零权重更新。
- 严谨地说，检索是**两错误问题**：漏检（相关记忆没被召回）与误检（不相关记忆被召回，产生干扰）。检索不是免费午餐：有索引/计算成本，也有负迁移。**更多记忆可能更差；核心不是索引多大，而是弃权（abstention）多准。**

**灵感 2（可重构机构：不是换硬件，而是在固定接口内换「执行构型」）**
- 可重构机构的本义是机构能在有限构型间切换（模块化机器人、变胞机构）。它的工程难点从来不是「能变」，而是**切换有代价、要避免抖动、每个构型都要可达且安全**。映射到策略：接口是死的（T_a、control_space、obs keys 在握手时固定，F20/F21/F28），但任务阶段的需求是变的——接近段要泛化，接触段要精确，偏离段要恢复，标称段要稳定。于是把「可重构」落在**执行构型**上：纯生成 / 记忆残差 / 记忆直执行 / 恢复，四档离散构型，**只在 chunk 边界切换**，带滞回与最小驻留。
- 严谨地说，可重构执行机构是一个带切换代价与驻留约束的离散状态机，而不是连续调参。反直觉点：**「自适应 chunk」在官方接口下是伪需求**——T_a 固定、chunk 整段执行；真正能重构的是「这一段由谁主导」，不是 chunk 长度。切换本身还要计入 p99 与动作规律性（F23），所以重构必须稀疏、可预测、可消融。

**两者咬合**：记忆提供「候选」，可重构机构决定「信不信、信多少、何时信」。记忆检索解决「先验从哪来」，可重构机构解决「先验怎么安全进入闭环」。两者都在推理期、零权重更新，天然适配单卡微调与共享 backend（F26/F22）。

**统一结论**：上一轮的数据引擎把「训练分布」搬进考纲；这一轮把「训练数据」变成「推理时可检索的机构」。**中期胜负手可能不是更大的模型，而是「参数记忆 + 非参数记忆 + 受约束重构」三件套。**

## 2. 关键数学事实：相对 EE 动作对起始位姿左不变（检索迁移的许可证）

官方把每个未来 EE 动作写成相对当前状态的变换（F24）：

$$a^{rel}_{t,k}=T_t^{-1}T_{t+k}\in SE(3).$$

若在测试时刻位姿 $T_{t'}$ 上复用记忆里从 $T_t$ 出发的同一段「体坐标系运动模式」，则目标位姿为

$$T'_{t'+k}=T_{t'}\,T_t^{-1}T_{t+k}.$$

其相对动作

$$T_{t'}^{-1}T'_{t'+k}=T_{t'}^{-1}T_{t'}T_t^{-1}T_{t+k}=T_t^{-1}T_{t+k}=a^{rel}_{t,k}.$$

**即：相对 EE 动作 chunk 对起始位姿左不变，可从任意当前位姿逐字复用。** 这解释了为什么「记忆片段」在动作空间里天然可迁移：检索真正要判断的不是位姿是否相同，而是**这段运动模式对当前物体/技能/阶段是否合适**。

边界条件：该性质只对 EE 相对动作成立；关节动作、夹爪绝对指令不具此不变性（夹爪开合可与物体尺寸耦合）。因此记忆迁移默认走 `ee` 控制空间；旋转部分用 Log/Exp 在切空间混合，避免直接线性插值旋转矩阵。

## 3. 对 v1.1 痛点的增量修订

- P2（泛化缺口）：检索给未见物品轴提供**非参数**通道，与 I1 的增广通道互补；但检索键若对背景/外观不具不变性，就会在该轴上恰好失效（见 PR7）。
- P4（无触觉）：恢复记忆只能依赖视觉偏离 + 进度停滞 + 本体一致性；触发信号必须多模态，不能只靠力。
- P5（时间压力）：T_a 固定意味着恢复只能发生在 chunk 边界；T_a 是设计期权衡（短=反应快但调用多、延迟抖动大；长=摊销好但恢复慢）。
- P8（示教质量）：I5 合成的「偏离→修正」段不仅是训练数据，更是 **I10 恢复记忆库**的原料。
- 新增 **P13 记忆浪费**：32k 成功 ep 被压成权重，具体片段不可寻址。
- 新增 **P14 静态接口 vs 动态需求**：接口固定，阶段需求变化，自适应只能落在构型而非接口。
- 新增 **P15 恢复触发延迟**：固定 T_a 下，恢复响应至少延迟一个 chunk。
- 新增 **P16 检索干扰**：误检注入错误先验，可能把原本会做的标称任务拖坏。

## 4. 研究问题（Q9–Q12，Q1–Q8 保留）

- **Q9（检索键的不变性-判别性）**：用什么键表示（DINOv2 / VLM / 多线索拼接）能在 5 条评分扰动轴上保持稳定，同时区分不同物体/技能/阶段？能否用 I1 的增广对自动构造正负样本，把检索键训练成「考纲不变」？
- **Q10（覆盖-精度-弃权）**：记忆库要多大、什么粒度（逐帧 / 逐 chunk / 逐子目标 / 恢复段）？在有限覆盖率下，弃权阈值如何校准到「误检率 < ε」？
- **Q11（可重构构型）**：四档构型（C0–C3）各自贡献多少？切换滞回与最小驻留如何设定，才能既恢复及时又不产生重构抖动（chattering）？
- **Q12（离线可证伪）**：检索效用（retrieval utility）与真机增益的相关性如何建立？哪些离线指标能替代真机 A/B？

## 5. 设计原则（新增 PR6–PR8，PR1–PR5 保留）

- **PR6 可重构预算律**：重构只允许发生在 chunk 边界；不改变已声明的接口（T_a / control_space / obs keys）；最小驻留 ≥2 chunks；切换成本计入 p99；每个构型必须可单独消融。违反任一条即降级为纯生成基线。
- **PR7 检索不变性律**：检索键必须经验证对评分扰动轴（背景、光照、干扰物、同类外观）不敏感，同时对技能/物体/阶段有判别力；未通过 L0 不变性测试的键不得进入计分通道。与 PR5 互补：PR5 管「数据教什么」，PR7 管「记忆按什么找」。
- **PR8 记忆只读与状态隔离律**：记忆库离线构建、评测期只读；评测期绝不写入记忆、不更新权重；共享索引可跨端口只读，但每端口工作记忆（working memory）必须隔离（F22）。这是「合法检索」与「违规在线适应」的分界线。

## 2. 形式化定义

### 2.1 四类只读记忆库

$$M_b=\{(k_i,v_i,\mu_i)\}_{i=1}^{n_b},\qquad b\in\{S,O,E,R\}$$

- **S（semantic/task）**：语言 + 任务 → 阶段序列、得分点里程碑、技能模式；
- **O（object/grasp）**：目标物体外观/几何 → 抓取点、夹爪开度、接近朝向（I9 v1.1 的升级）；
- **E（episodic）**：状态关键帧 → 相对 EE 动作 chunk；
- **R（recovery）**：偏离状态 → 修正段（来自 I5 合成 + 真机回放）。

键 $k=\phi(o,\ell,s)$（物体裁剪嵌入 + 指令嵌入 + 阶段/本体标量）；值 $v$ 统一为**相对 EE 动作 chunk**（可含夹爪序列）；元数据 $\mu$ = task / phase / object / q-score / source。

### 2.2 检索、门控、注入

检索 top-k：

$$\mathcal{N}_k(q)=\operatorname{topk}_{i}\ \exp\!\left(-d(q,k_i)/T\right),$$

其中 $d$ 为归一化键上的余弦距离或 L2。弃权门控：

$$g(q)=\mathbb{1}[d_{(1)}<\tau_{\text{in}}]\cdot\mathbb{1}[d_{(2)}-d_{(1)}>\delta]\cdot\mathbb{1}[\mathrm{Agr}(v_{(1..k)})>\alpha].$$

后两项是抗干扰核心：**距离裕度**排除「两个技能都很像」的模糊态，**动作一致性**排除「最近邻彼此矛盾」的误检。$g=0$ 时弃权，退回纯生成。

先验与注入（在 se(3) 切空间混合，旋转用 Log/Exp）：

$$\bar v=\sum_{i\in\mathcal{N}_k}w_i v_i,\qquad w_i=\frac{e^{-d_i/T}}{\sum_j e^{-d_j/T}},$$

$$a=a_\theta(o)\oplus\lambda\bar v.$$

$\lambda$ 按构型取：C0 为 0，C1/C3 为自动门控值，C2 为 1。检索效用：

$$U=\mathbb{E}[\Delta\mathrm{prog}\mid\text{retrieved}]-c_{\text{lat}}\mathbb{E}[\Delta t]-c_{\text{int}}\Pr[\text{commission}].$$

$U\le 0$ 的库/键/阈值不得进入计分通道。

### 2.3 检索键的不变性-判别性目标

设 $\mathcal{A}$ 为评分扰动轴（背景、光照、干扰物、同类外观）。要求

$$\min_\phi\ \mathbb{E}_{o}\Big[\max_{a\in\mathcal{A}}d(\phi(o),\phi(T_a o))\Big]-\beta\,\mathbb{E}_{(o,o')\text{ 不同技能}}\Big[\max(0,m-d(\phi(o),\phi(o')))\Big].$$

正样本对由 I1 的考纲增广器生成（同一物体/技能、施加扰动轴），负样本来自不同物体类/技能/阶段。实现：DINOv2 patch 池化 + 指令嵌入 + 阶段标量，投影到 128–256 维；可训练一个轻量投影头，不必重训 VLA。

### 2.4 可重构执行机构（REM）

$$\mathcal{R}=(\mathcal{C},\sigma,\mathcal{H},D,\mathcal{G})$$

- $\mathcal{C}=\{C_0,C_1,C_2,C_3\}$：离散执行构型；
- $\sigma(o,s)\to c$：由不确定度 $u$、进度停滞 $\pi$、检索置信 $\rho$、阶段 $s$ 决定的切换函数；
- $\mathcal{H}$：滞回（进入阈值 $\tau^\uparrow$ > 退出阈值 $\tau^\downarrow$）；
- $D\ge2$：最小驻留（以 chunk 计）；
- $\mathcal{G}$：安全护栏与回退（越界/超速/不平滑 → 回 C0）。

抖动率：

$$\chi=\frac{1}{N}\sum_{n}\mathbb{1}[c_{n+1}\ne c_n],$$

约束 $\chi\le\chi_{\max}$（建议 ≤0.15/chunk）。可达性：每个构型必须在当前控制空间合法且能通过 $\mathcal{G}$，否则不可进入。切换只在 chunk 边界；检索只在切换 chunk 上发生，摊销进 p99。

## 4. 重点创新点

### I9 v2 HMRR（Hierarchical & Metamorphic Retrieval，分层可重构记忆检索）★★★★★

- **动机**：v1.1 只在 `reset()` 做一次物体检索，覆盖「未见物品轴」的一部分；但 32k 示教的可用信息远不止物体参数——还有技能段、阶段先验、恢复段。且 v1.1 没有弃权机制，误检索会直接伤标称任务。
- **与 v1.1 差异**：① 单库 → 四库（S/O/E/R）；② 单次 reset → reset + 子目标切换 + 停滞触发的多阶段检索；③ 无门控 → 距离/裕度/一致性三重弃权；④ 明确只读与每端口隔离（PR8）。
- **技术可行性**：中-高。索引离线构建；检索 <5ms/次（1M 向量、fp16、FAISS/HNSW）；无需重训 VLA；可选 LoRA 让动作头消费先验（F26）。
- **落地步骤**：① 用 32 任务 + 110 语料 + DiverseManip 构建四库；② 训练/固定检索键并做不变性测试（PR7）；③ 校准弃权阈值（目标误检率 <5%）；④ 实现残差注入；⑤ L0 离线效用与标称伤害；⑥ L2 真机抽测。
- **风险**：检索干扰（缓解：弃权 + 残差 + 只在非标称/高不确定时启用）；键对评分轴不不变（缓解：I1 正样本对训练 + L0 轴偏移测试）；覆盖不足（缓解：弃权退回生成）；延迟（缓解：只在 reset/切换点检索）。

### I10 RCM（Recovery Case Memory，记忆驱动恢复案例检索）★★★★

- **动机**：步骤分与成功率都受「偏离后能否修正」支配（F25）；数据集全成功、无失败示教（P8）；I5 v3 已能合成「偏离→修正」段，但这些段只在训练时被用掉，推理时没有被检索。
- **机制**：从 I5 合成恢复段 + 真机回放构建 R 库；触发信号 = 进度头停滞（$\pi$）+ 视觉偏离（关键点/物体位姿）+ 动作不确定度；检索最近恢复段，与生成式动作残差混合；里程碑检测器确认「是否达成下一得分点」，未达成则丢弃本次注入并回 C0。
- **与 v1.0 差异**：v1.0 是手写「回退-重接近-重抓」原语（新分布、可能违反单模型边界）；RCM 恢复行为来自示教分布，零权重更新，且可随 I5 数据扩张而增强。
- **落地步骤**：① R 库 schema 与质量门禁；② 触发阈值标定（3 个弱任务：PlugCharger/ZipUp/PourOutMedicine）；③ 安全护栏（严格模式）；④ 与 I4 人手干预状态机互斥（有人在场时不得自动恢复）；⑤ L0 回放 + L2 A/B。
- **风险**：误触发（缓解：多信号与滞回）；恢复段与当前偏离不匹配（缓解：键含偏离类型/阶段，检索后先做一致性校验）；恢复延迟 ≥1 chunk（缓解：T_a 取 4–8，并优先在 chunk 边界前预取）。

### I11 REM（Reconfigurable Execution Mechanism，可重构执行机构）★★★★

| 构型 | 主导 | 记忆 | 护栏 | 适用 |
|---|---|---|---|---|
| C0 纯生成 | VLA 动作头 | 关闭 | 全量 | 标称、低不确定、默认 |
| C1 记忆残差 | VLA + O/E 先验 | 软残差 | 全量 | 未见外观、轻度不确定 |
| C2 记忆直执行 | E/O 片段 | 直接执行 | 严格 | 高置信、分布内、接触段 |
| C3 恢复 | R 片段 + 生成修正 | 恢复库 | 严格 | 进度停滞/视觉偏离 |

- **切换信号**：多采样动作方差/一致性 $u$、进度头停滞 $\pi$、检索距离裕度 $\rho$、阶段 $s$。
- **防抖**：进入/退出阈值滞回 + 最小驻留 $D\ge2$ chunks + 抖动率预算；强制 C0 作为安全回退。
- **与 I4 的关系**：人手检测到干预时强制 C0/停持，不进入 C3；恢复只在无人干预时启用。
- **落地步骤**：① 定义信号与阈值；② 实现构型状态机（每端口独立）；③ L0 用留出集回放模拟切换（离线估计抖动率与延迟）；④ L1 部分析因；⑤ L2 真机。
- **风险**：抖动（缓解：滞回 + 驻留 + 抖动率门禁）；切换成本（缓解：只在 chunk 边界、预取索引）；C2/C3 安全性（缓解：严格护栏 + 里程碑校验 + 失败回 C0）。

### I4 修正（自适应 chunk → chunk 边界构型切换）

F20 确认 `action_chunk_size` 握手固定、chunk 整段执行，v1.1 的「干预态短 chunk / 稳定态长 chunk」在接口上不可实现。修正为：保留手部检测、停持、重估状态机；自适应落在 **I11 的构型切换** 与 **固定 T_a 下的承诺策略**（例如选择 T_a=8 的折中，或在 chunk 内后段填入更保守的外推）。优先级下调。

### I7 裁撤（推理路径）

测试时世界模型前瞻需要额外 rollout，直接冲击 p99 与动作规律性（F23），且与 I10 的恢复记忆功能重叠。裁撤推理路径；WMA-0 仅作**离线**稀有偏离帧生成器，服务 R 库构建（裁撤不等于废弃）。

### 维持项速览

- **I1 v3**：考纲校准五轴增广；新增用途——为检索键生成正样本对（同一物体/技能 + 评分轴扰动）。

def build_memory(dataset, phi, stride=8, H=8):
    banks = {b: [] for b in "SOER"}
    for ep in dataset:
        for t in range(0, len(ep), stride):
            o, lang = ep.obs[t], ep.language
            phase = phase_of(ep, t)

### 5.2 reset + chunk 边界重构（每端口状态隔离）

```python
class ReconfigurablePolicy:
    CONFIGS = {
        "C0": dict(bank=None, lam=0.0, guard="full"),     # 纯生成
        "C1": dict(bank="OE", lam="auto", guard="full"),  # 记忆残差
        "C2": dict(bank="EO", lam=1.0, guard="strict"),   # 记忆直执行
        "C3": dict(bank="R", lam="auto", guard="strict"), # 恢复
    }

    def reset(self):
        self.ws = FreshWorkingState()   # 每端口/每 episode 隔离（F22）
        self.cfg, self.dwell = "C0", 0
        self.stall, self.p_last = 0, 0.0

    def get_action(self, obs):
        sig = self.signals(obs)                  # u, pi, rho, phase
        nxt = self.switch(self.cfg, sig)         # 带滞回的状态机
        if nxt != self.cfg:
            if self.dwell < self.MIN_DWELL and not self.forced(nxt):
                nxt = self.cfg
            else:
                self.cfg, self.dwell = nxt, 0
        cfg = self.CONFIGS[self.cfg]

        a_gen = self.vla.propose_chunk(obs)      # 基座生成
        a = a_gen
        if cfg["bank"] and self.retrieval_due():
            hits = retrieve_gate(self.banks, self.key(obs), cfg)
            if hits is not None and self.consistent(hits, obs):
                a = inject(a_gen, hits, cfg["lam"])   # se(3) 切空间残差
        a = self.guard(a, obs, strict=(cfg["guard"] == "strict"))
        self.dwell += 1
        return a
```

## 6. 实验设计（分级消融 v3）

| 级别 | 内容 | 通道/成本 | 通过判据 |
|---|---|---|---|
| L0 | 检索键不变性/判别性；四库 recall@k 与误检；注入效用与标称伤害；抖动率离线回放；延迟 | 离线，免费 | 误检 <5%；标称 Δprog ≥0；utility >0；p99 预算内 |
| L1 | 2^(k-p) 部分析因：库×门控×注入×构型；T_a∈{4,8,16,30}；驻留 D∈{1,2,4} | 离线 + 少量真机 | 主效应显著的 ≤3 个组合进 L2 |
| L2 | top 组合真机：≥2 任务×各 ≥2 次；含 3 个弱任务 + 2 个未见物品任务 | 单任务通道 | 真机增益 ≥ 离线预测的 50%；p99 与抖动率不超门禁 |
| 门禁 | PR4：run_client 全流程 + p99 + 动作健康度 + 抖动率 | 本地 stub | 0 拒绝动作、p99 < 40ms、χ ≤0.15 |

**消融矩阵（最小集）**

- 键：像素 / DINOv2 / DINOv2+指令 / +阶段 / 对比学习键；
- 库：无 / O / O+E / +R / 全；
- 门控：无 / 距离 / +裕度 / +一致性；
- 注入：无 / 软残差 / 直执行；
- 构型：C0 / C0+C1 / +C2 / +C3；
- T_a：4 / 8 / 16 / 30；驻留 D：1 / 2 / 4。

**止损判据（Kill Criteria）**

1. 某库 L0 误检 >10% → 收紧门控；>20% → 该库不上计分通道。
2. 标称场景 Δprog <0 → 检索只在非标称/高不确定时启用。
3. utility ≤0 或只在本征匹配（同场景记忆）上有效 → 视为「查训练集」，不计入泛化收益，回退。
4. p99 超预算或抖动率 >χ_max → 降低检索频率 / 增大驻留 / 只在 reset 检索。
5. L2 真机增益 < 离线预测 50% → 降级 I9/I10，保留 I11 的 C0/C1。

**首批 L2 排队**：① I9 v1 基线（reset 单库）→ ② I9 v2 四库（C1）→ ③ I10 RCM（C3，3 个弱任务）→ ④ I11 构型机（C0–C3 对比 + 抖动率）。

## 10. 本轮最值得押注 + 最大风险

**最值得押注**：**I9 v2（四库只读检索 + 弃权）× I10（恢复案例记忆）× I11（chunk 边界构型机）**。理由：三者共享同一套基础设施（相对 EE 动作左不变、离线索引、每端口状态隔离），成本集中在数据与索引而非重训模型；先手窗口在于「记忆覆盖 + 键不变性 + 弃权校准」，而不是模型规模。I7 的推理路径裁撤后，世界模型资产转为离线记忆生成，算力更集中。

**最大风险（一句话）**：记忆检索可能在真正计分的泛化轴上恰好失效——若检索键对背景/外观等扰动不具不变性、又缺乏可靠弃权，检索注入的先验会把原本会做的标称任务拖坏；叠加固定 T_a 的恢复延迟，「记忆红利」可能变成「干扰与延迟负债」。
