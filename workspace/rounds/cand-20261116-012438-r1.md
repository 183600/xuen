# 第 12 轮（新灵感循环第 1 轮；本轮灵感：「双臂协作」×「需求洞察」）
> **基线**：第 11 轮 MetricVoiceGauge-GSCF-SRA-JSSE（定义 549–561；引理 92–96；实验 E591–E610）。
> 本轮纪律：**协作可证 + 需求可证 + 承诺可退**。v11 把单臂「动作级安全」做到极致，却留下三笔债：**协作债**（所有证书——Ĉ⁺⁺、JSSE、Q_abort——都以单臂为单位；双臂共享物体时「每臂安全」不等于「团队安全」：互撞、相对位姿漂移、内力/挤压、载荷失衡、协调中止均无机制）、**意图债**（NRB 管规范、SRA 管语义，但没有「用户到底要什么」的可证表示；系统可能安全地做错事，或因过度保守而不好用）、**承诺债**（v11 的退化是模块级中立元，缺少「谁在何时承诺了什么」的显式对象；三守护共失效时只能急停，无法按任务承诺优雅降级）。两个灵感分别从「团队物理」与「目的对齐」两侧切入，合起来治理三笔债。铁律不变：新模块失效 ⇒ 注入声明中立元，行为**严格等价或支配**于 v11（BCE/NIC/RCS 失效时只允许退回 v11 的认证可行集）。

## 0. 直觉与动机

**灵感 1（双臂协作 → 从「每臂安全」升级为「成对证书」）**
直觉：单臂证书回答「这只手能不能安全地做这个动作」，双臂问题回答「两只手合起来是否仍然安全」。后者不是前者之和：共享刚体把两臂耦合成一个过约束系统，内力不可观、相对位姿会漂、载荷会转移、双臂互相成为动态障碍；更麻烦的是，**中止也是耦合的**——一只手中止而另一只手持物，可能把物体扯坏或甩出。核心创新：**双臂协作包络（Bimanual Coordination Envelope, BCE）**——在 v11 每臂 Ĉ⁺⁺ 之上加一层**成对证书** Ĉ^bi=(Ĉ_L⁺⁺,Ĉ_R⁺⁺,ρ_rel,m_fc^bi,m_sq,n_need,r,Q_abort^bi)：相对位姿余量 ρ_rel、双臂力封闭余量 m_fc^bi、挤压余量 m_sq、载荷比；安全集合取「两臂 v11 安全集之积 ∩ 互障距离 ∩ 相对位姿/内力/载荷约束」；1kHz 侧用**互惠屏障投影**（每臂把另一臂的保守扫掠体当障碍）把互撞证明降为 O(1) 的集合包含论证；中止用**解耦算子** D_r 按「耦合保持 → 单臂保持+另臂退避 → 受控放下 → 协调急停」四级降级。理论上关键一步：**成对证书的组合性**——两臂各自 v11 证书 + 相对证书 ⇒ 团队动作在 C_{q2,safe} 内（引理 103）；任一臂/相对证书失效 ⇒ 沿角色格降级，最终严格回到 v11（引理 105）。

**灵感 2（需求洞察 → 从「给定任务」升级为「可证需求」）**
直觉：v11 的 NRB 回答「这样做合不合规范」，SRA 回答「这样理解对不对」，但没有人回答「用户到底要什么、这个需求此刻可不可满足、不确定时该不该问」。需求洞察若只是「读心/猜意图」，会把语义幻觉直接放大成任务错误；更糟的是它可能被当作新的授权来源。核心创新：**需求洞察契约（Need-Insight Contract, NIC）**——需求不是隐藏向量，而是**带证据、版本、置信度与不确定集的可证假设** h=(G_h,⪯_h,U_h,c_h,ver)；系统只对落在**可满足需求包络（Satisfiable Need Envelope, SNE）**内的需求行动：SNE 中的每个目标 g 必须对应一个**已认证计划** π∈Π_cert(g)（v11 或 BCE 证书）与一个需求证书 Ĉ^need=(g,sat,coverage,conf,evidence,ttl)。关键不是「更准地猜」，而是**把猜错限制在效用层**：需求只允许在已认证计划集合中选择/收窄目标（P17 需求不越权），绝不放宽安全；不确定时先**有界澄清**（Clarify，≤2 问/≤3s），仍不确定则执行**安全的局部履行/规范回退**并披露（P18 需求可满足）。这正面回应 v11 最大风险：「三守护虚假低 ⇒ 只能急停」——现在可以先退到「仍满足用户可接受子需求」的较简单角色，而不是全盘停机。

**灵感 3（咬合：共享承诺 → 把需求与协作绑成一条可退的链）**
直觉：需求是「为什么做」，角色是「谁来做」，成对证书是「这样做安不安全」。三者如果不显式绑定，就会出现最危险的缝隙：需求被悄悄改写、角色在运行时漂移、证书只对旧承诺有效。核心创新：**角色承诺调度器（Role Commitment Scheduler, RCS）**与**承诺台账（Λ^commit）**：需求→有限角色库 R_cert（≤8，每个角色预认证入口/出口/资源）→成对证书→承诺对象 c=(h,g,r,π,Ĉ^bi,exit,ver)。原则 P19 **最小耦合律**：能用单臂解决就绝不上双臂，能松耦合就不上刚耦合；P20 **承诺可退律**：每个承诺都带一条有界解耦路径到 v11，台账缺口即触发收缩。这样双臂协作不是「更强但更危险」，而是「在需求确实需要时才申请、且随时可退的受限能力」。

三者的证书链：NIC 出**需求通过向量** n_need 与目标 g，RCS 出**角色配置** r，BCE 出**成对证书** Ĉ^bi，v11 出每臂 Ĉ⁺⁺ 与五检。最终块证书升级为 **Ĉ_t^{iv}=(Ĉ_L⁺⁺,Ĉ_R⁺⁺,ρ_rel,m_fc^bi,m_sq,n_need,r,c_id,Q_abort^bi)**。

## 1. 研究问题（轮次升级版）

- **Q1（协作可证）**：如何把单臂证书组合成可证的双臂成对证书，使互撞/相对位姿/内力/载荷四类耦合失效在 ≤1 个控制拍内被发现，且任一双臂模块失效时行为可证支配于 v11？
- **Q2（需求可证）**：如何把「用户要什么」形式化为带证据与版本的需求假设，使系统只在可满足需求包络内行动，错需求只损失效用不破坏安全，并把澄清/披露/纠错做成有界、可审计的流程？
- **Q3（承诺可退）**：如何用有限角色库与承诺台账把需求、角色、成对证书绑成一条可退链，使「三守护共失效」从「只能急停」变成「有界降级到仍可用的 v11 子任务」，同时安全不高于 v11？

## 2. 设计原则（在 P13–P15 基础上新增 P16–P20）

**P16 协作可证律（BCE）**
双臂动作必须持有成对证书 Ĉ^bi；每臂 Ĉ⁺⁺ 与相对证书缺一不可；共享物体不得被当作安全保证，只被当作受约束的耦合对象。

**P17 需求不越权律（NIC）**
需求/角色只可在已认证计划集合内选择或收窄目标，不可扩权、不可放宽 v11/BCE 阈值、不可生成新动作；需求不确定 ⇒ 澄清/局部履行/规范回退。

**P18 需求可满足律（NIC）**
只对 SNE 内需求行动；Ĉ^need 必须给出已认证计划见证与覆盖/置信/新鲜度；不可满足时必须拒绝或安全局部履行并披露，禁止静默猜测。

**P19 最小耦合律（RCS）**
选择能满足当前需求的最少耦合角色；单臂够用不上双臂，松耦合够用不上刚耦合；耦合是「申请来的受限能力」，不是默认能力。

**P20 承诺可退律（RCS/BCE）**
每个承诺都带入口不变式、出口 e_c、有界解耦路径 D_r 与资源配额；解耦须在 B_dec 内回到 v11 认证态或更松角色，台账缺口/版本不匹配 ⇒ 立即收缩。

## 3. 与基线的接口（如何退化）

- BCE 失效（相对位姿不可测/力传感器失效/成对证书不可得/同步超限）⇒ r←r_0∈{单臂保持,单臂操作}，成对证书退出，行为**等价 v11 单臂**；共享物体按解耦算子受控放下或单臂保持；
- NIC 失效（需求推断超时/OOD/证据链断/台账缺口）⇒ n_need←0、g←g_0（v11 规范任务），只走 v11 单臂路径，**等价 v11**；已发澄清问题作废，披露一次；
- RCS 失效/角色库版本不匹配 ⇒ r←r_0，**等价 v11**；空库 ⇒ 仅 v11；
- 任一臂 v11 模块（GSCF/SRA/JSSE/STF/NRB/AC/ID/MW）失效 ⇒ 沿 v11 九级退化链原样；对侧臂不得因「队友还在」而放宽自己的证书——**单臂证书不因协作而放松**；
- v8 及更早 ⇒ 中立元注入 ⇒ v7 ⇒ v6。

## 4. 预期贡献

1. **成对证书与角色降级格**：把双臂安全从「两臂各自安全」升级为可组合、可退化、可审计的团队证书（引理 103–105）；
2. **可证需求洞察**：需求假设 + SNE + 需求证书 + 有界澄清，使「错需求」被限制在效用层，安全对 v11 单调不降（引理 106–107）；
3. **承诺化降级**：需求→角色→证书的承诺链与最小耦合/承诺可退原则，把三守护共失效从「急停」变成「有界降级」（引理 108）；
4. **E631–E650** 覆盖成对组合、相对位姿、内力/挤压、互撞、协调中止、角色降级、需求标定、对抗需求、长跑与竞赛。

## 5. 本轮最大风险

**一句话**：需求洞察是整个系统中唯一无法被安全证书兜底的环节——一个高置信的错需求会让系统去严谨地证明「如何把一件不该做的事做对」，而双臂的高耦合会把这种目的层错误通过共享物体放大为物理后果；角色降级格只能在「已承诺的需求」内部收缩，无法自动发现承诺本身错了。

**新增定义 562（双臂角色配置）** 角色配置 r=(role_L,role_R,mode,I_r,e_r,ρ_r)，role∈{HOLD,MANIPULATE,SUPPORT,FREE}，mode∈{INDEPENDENT, LEADER_FOLLOWER, BIMANUAL_COMPLIANT, BIMANUAL_RIGID}。R_cert={r_0,…,r_7}，|R_cert|≤8，r_0=INDEPENDENT 即 v11 单臂路径。每个 r 预认证：∀s∈I_r，执行 r 至多 T_r 的轨迹 R_r(s)⊆C_{q2,safe}，且出口 e_r(s) 为 v11 认证中止或更松角色 r'≺_R r。耦合度偏序：INDEPENDENT ⪯ LEADER_FOLLOWER ⪯ BIMANUAL_COMPLIANT ⪯ BIMANUAL_RIGID，r_0 为底。

**新增定义 563（双臂安全集合）**
```
C_{q2,safe} = (C_{q,safe}^L × C_{q,safe}^R) ∩ C_cross
C_cross = { (q_L,q_R) |
    ∀a∈links(L), b∈links(R): d(a,b) ≥ d_cross
    ∧ ‖e_rel‖_W ≤ ε_rel
    ∧ ‖Ṫ_rel‖ ≤ v_rel
    ∧ (mode ∉ {BIMANUAL_COMPLIANT,RIGID} ∨ (
          m_fc^bi ≥ m_min^bi ∧ m_sq ≥ m_sq,min ∧ λ_L∈[λ_min,λ_max]))
    ∧ 共享物体与两臂扫掠体均无环境碰撞
    ∧ ZMP(q) ∈ support_polygon^bi }
```
其中 C_{q,safe}^i 为 v11 定义 556。**C_cross 只增加约束，不替换 v11 每臂约束。**

**新增定义 564（相对位姿证书）** 令 T_rel=T_L⁻¹T_R，目标 T_rel^*；残差 e_rel=Log((T_rel^*)⁻¹T_rel)∈se(3)。余量 ρ_rel=1−‖e_rel‖_W/ε_rel，W 为位置/姿态对角权重。ρ_rel≥ρ_min 为有效条件；同时要求相对速度 ‖Ṫ_rel‖≤v_rel，防止过约束拉扯。ρ_min、ε_rel、v_rel 由 E632 标定；刚耦合模式取较大 ε_rel，柔性模式用阻抗吸收残差。**ρ_rel 是相对证书的领先指标（相对位姿每拍可测），不是事后统计。**

**新增定义 565（双臂力封闭与挤压余量）** 接触集 C_L、C_R，联合抓取矩阵 G^bi=[G_L G_R]，扰动集 W（物体重力+惯性+有界外力）。带余量摩擦锥：
```
FC_α^bi = { λ | ∀接触: ‖f_t‖ ≤ (μ−α)f_n, f_n∈[f_n,min,f_n,max],
                  λ_L,λ_R∈[λ_min,λ_max] }
m_fc^bi = sup{ α∈[0,min μ] | ∀w∈W, ∃λ∈FC_α^bi: G^bi λ = −w }
m_sq = (f_crush,max − Σ f_n) / f_crush,max
```
m_fc^bi>0 表示对 W 的鲁棒力封闭；m_sq>0 表示未逼近压碎力。两余量均达标才允许 BIMANUAL_RIGID；否则降为 BIMANUAL_COMPLIANT 或单臂。m_min^bi、m_sq,min 由 E633 标定。

**新增定义 566（成对证书）**
```
Ĉ^bi = (Ĉ_L⁺⁺, Ĉ_R⁺⁺, ρ_rel, m_fc^bi, m_sq, n_need, r, c_id, Q_abort^bi)
```
有效 ⇔ 两臂 Ĉ⁺⁺ 各自有效 ∧ r∈R_cert ∧ I_r(s) 成立 ∧ ρ_rel≥ρ_min ∧（mode≠RIGID ∨（m_fc^bi≥m_min^bi ∧ m_sq≥m_sq,min））∧ 同步 |τ_L−τ_R|≤τ_sync ∧ n_need=1 ∧ Q_abort^bi≠∅ ∧ c_id 与当前承诺一致。**成对证书只增加证据或触发收缩，绝不放宽任一臂的 ĝ_min/ê_max/β_GSCF。**

**新增定义 567（互惠屏障投影）** 对每臂 i，令 V̂_j(t) 为对侧臂下一控制拍的保守扫掠体（实际可达体积 V_j⊆V̂_j）。投影：
```
q_i^cmd ← Proj_{C_i^recip}(q_i^raw)
C_i^recip = C_{q,safe}^i ∩ { q_i | dist(link_i(q_i), V̂_j(t)) ≥ margin }
```
保守模式两侧均取 margin=d_cross（冗余，无需监视器即可证互撞距离≥d_cross）；均衡模式两侧取 margin=d_cross/2，并由 1kHz 距离监视器在实测 d<d_cross 时触发双腕协调保持；监视器失效 ⇒ 立即回保守模式。**任一臂的屏障健康即可单独保证 d(L,R)≥d_cross（引理 104），因此单臂预测失败不破坏互不碰撞。**

**新增定义 568（协调中止与解耦算子）**
```
Q_abort^bi = { (q_L,q_R) | q_i∈C_{q,safe}^i, FK_i(q_i)=p_i^*±ε_fk,
               ‖e_rel‖≤ε_rel^abort, object_state∈{HELD_SECURE,PLACED_SAFE} }
```
解耦算子 D_r 按四级优先返回下一角色/中止：
1. **COUPLED_RETREAT**：双腕沿相对刚体路径退到保持位（需 ρ_rel 保持）；
2. **HOLD_AND_SINGLE_ABORT**：一臂保持（需单臂 m_fc≥m_min^single 或物体有支撑），另一臂执行 v11 中止；
3. **CONTROLLED_PLACE**：在 d_stop 内把物体放到最近认证支撑面，再双腕独立中止；
4. **COORDINATED_ESTOP**：双腕零速保持+重力补偿（等价 v6 级）。
**每个 D_r 的出口必须是更松角色或 v11 认证中止。**

**新增定义 569（角色降级格）** (R_cert,⪯_R) 为有限格；D_r: R_cert→R_cert∪{v11 abort} 满足 D_r(r)≺_R r（r≠r_0）。深度 depth(r)≤4。降级必须沿格下降，禁止跳回更耦合角色；回到更耦合需重新走 NIC/RCS 认证并生成**新承诺**（新 c_id），不许复用旧证书。

**新增定义 570（需求假设）** 需求原子 n=(φ,scope,src,e,c,ver)，φ 为世界/历史状态谓词，scope 为对象/房间/人，src∈{语音,手势,注视,上下文,历史,模板}，e 为证据哈希，c 为置信度。需求假设 h=(G_h,⪯_h,U_h,c_h,ver,ttl)，G_h⊆G_lib 为候选目标集，⪯_h 为偏好偏序，U_h 为不确定备选集，ttl 为新鲜度。**h 只是假设，不是命令；它没有授权效果（P17）。**

**新增定义 571（可满足需求包络 SNE）** G_lib 为有限目标模板库（|G_lib|≤64，与 NRB 谓词表同构），每个 g∈G_lib 带参数域与预认证计划族 Π_cert(g)（v11 单臂或 BCE 双臂）。

```
SNE = { h | ∃g∈G_h, π∈Π_cert(g):

```
判定 sat(h)∈{FULL,PARTIAL,NONE}：FULL=存在直接认证计划；PARTIAL=存在 g'⪯_h g 的安全子目标/局部计划；NONE=库内无认证计划。**SNE 只缩小可行动集，不产生新计划。**

**新增定义 572（需求证书）** Ĉ^need=(g,params,sat,coverage,conf,evidence,ttl,ver)。有效 ⇔ sat≠NONE ∧ conf≥τ_need(Rev(g)) ∧ 未过期 ∧ 与当前世界状态不矛盾 ∧ 见证哈希可查。n_need=1 ⇔ Ĉ^need 有效。R2 目标额外要求显式确认（定义 575）。

**新增定义 573（有界澄清算子）** Clarify(h) 从模板集 Q_clar（|Q_clar|≤8）选一个最大化期望信息增益/成本比的问题；预算 N_q≤2、T_clar≤3s。无可用问题或预算耗尽 ⇒ 不行动于该需求，改执行**安全局部履行** g'⪯_h g（PARTIAL）或规范回退 g_0（v11 任务），并语音披露。澄清答案作为新证据更新 h，**不直接改安全阈值**。

**新增定义 574（需求不越权）** 令 Adm(s) 由（v11/BCE 证书、守卫、规范、预算）唯一决定，不含 h。则 ∀h（含错误/对抗 h）：Adm_h(s)=Adm(s)，且被执行的 π∈Π_cert(g)⊆Adm(s)。**推断/学习只能改变 g 与 π 的排序，不能改变 Adm。**

**新增定义 575（可逆性分级与确认门槛）** Rev(g)∈{R0,R1,R2}：R0 可逆（取放、观察、让路）；R1 可补偿（移动未注册物品、改变布置）；R2 不可逆（触碰人、破坏/隐私暴露、单程搬运）。τ_need(R0)≤τ_need(R1)≤τ_need(R2)；R2 必须显式确认（语音/界面），确认本身入台账。**确认不改变 Adm，只改变是否允许发起该 g。**

**新增定义 576（承诺对象）** c=(h,g,r,π,Ĉ^bi,exit,ver,owner,t0,t1)。状态∈{PROPOSED,ACTIVE,SUSPENDED,FULFILLED,REVOKED,DEGRADED}。c 有效 ⇔ Ĉ^bi 有效 ∧ Ĉ^need 有效 ∧ r 的入口不变式成立 ∧ 版本匹配。需求修订 ⇒ c←REVOKED 或 DEGRADED（若存在安全局部履行）；**不得静默替换 h**。

**新增定义 577（承诺台账）** Λ^commit 在 v10/v11 哈希链上追加：

**新增定义 578（扩展块证书与成对有效块长）**

**新增定义 580（三维度量）**

## 2. 形式化定义（要点与升级）

**定义 493/495/521/496/531/539/540–561** 继承 v11。δ_trigger 五条件中「Ĉ_t⁺⁺ valid」升级为「Ĉ_t^{iv} valid」（含成对证书、需求证书、承诺版本），块证书失效、单步条件与承诺撤销同样触发 M₀ 硬检查。

**升级定义 539（有效块长，v12）**：每臂 K_eff 公式**完全沿用 v11 定义 553**；成对块长取 K_eff^bi=min(K_eff^L,K_eff^R)，再由定义 578 的成对条件进一步截断。**BCE/NIC/RCS 不得修改任一只臂的 K_eff 公式**；它们只能缩短成对块长或退回单臂。

**升级定义 559（五检 + 成对守卫，v12）**：每臂 50Hz 五检（证书有效性、停车不变式、语义创新度、快规范、几何一致性）不变；新增 **500Hz 成对守卫（四检）**：
1. 相对位姿：ρ_rel≥ρ_min；
2. 内力/挤压：刚耦合时 m_fc^bi≥m_min^bi ∧ m_sq≥m_sq,min；
3. 互障：d(L,R)≥d_cross（另有 1kHz O(1) 距离屏障）；
4. 同步/承诺：|τ_L−τ_R|≤τ_sync ∧ n_need=1 ∧ c_id 匹配。
任一失败 ⇒ 走 D_r 解耦，而不是直接急停；若 D_r 也不可行 ⇒ v11 中止/协调急停。

**新增定义 581（承诺感知触发）**
```
Trigger_commit = 五检失败 ∨ 成对守卫失败 ∨ 需求漂移超阈
                 ∨ 澄清/确认超时 ∨ 台账缺口
```
Trigger_commit 时，若存在更松角色且其入口不变式成立 ⇒ 降级并生成新承诺；否则退回 v11 单臂/中止。**正常周期不得进入降级路径，防止降级成为常态绕路。**

```python
class BimanualCoordinationEnvelope:
    """成对证书：两臂 v11 证书之外只增加约束，绝不放宽。"""
    def __init__(self, jsse_l, jsse_r, kin, dyn, d_cross, eps_rel, rho_min,
                 m_min_bi, m_sq_min, tau_sync, roles, f_crush_max):
        self.jsse_l, self.jsse_r = jsse_l, jsse_r
        self.kin, self.dyn = kin, dyn
        self.d_cross, self.eps_rel, self.rho_min = d_cross, eps_rel, rho_min
        self.m_min_bi, self.m_sq_min, self.tau_sync = m_min_bi, m_sq_min, tau_sync
        self.roles, self.f_crush_max = roles, f_crush_max
        self.m_fc_bi, self.m_sq, self.rho_rel = 0.0, 1.0, 0.0

    def relative_cert(self, T_l, T_r, T_rel_star):
        e = log_se3(inv(T_rel_star) @ inv(T_l) @ T_r)
        self.rho_rel = 1.0 - norm_W(e) / self.eps_rel
        return self.rho_rel, e

    def force_closure(self, contacts_l, contacts_r, W, mu, load):
        G = combined_grasp_matrix(contacts_l, contacts_r)
        self.m_fc_bi = max_alpha_in_friction_cones(
            G, W, mu, load, warm_start=self._lp_warm)   # 小 LP，m≤8
        self.m_sq = (self.f_crush_max - sum(load.fn)) / self.f_crush_max
        return self.m_fc_bi, self.m_sq

    def pair_guard(self, chunk, live):
        """500Hz 四检，O(k)。失败返回原因，交给 decouple。"""
        if not (chunk.cert_l.valid and chunk.cert_r.valid):
            return "arm_cert"
        rho, _ = self.relative_cert(live.T_l, live.T_r, chunk.T_rel_star)
        if rho < self.rho_min:
            return "relative"
        if chunk.role.mode == "RIGID":
            if self.m_fc_bi < self.m_min_bi or self.m_sq < self.m_sq_min:
                return "internal_wrench"
        if live.d_interarm < self.d_cross:
            return "collision"
        if abs(live.tau_l - live.tau_r) > self.tau_sync:
            return "sync"
        if not (live.n_need and live.c_id == chunk.c_id):
            return "commitment"
        return None

    def reciprocal_project(self, q_l_raw, q_r_raw, swept_l, swept_r,
                           mode="conservative"):
        margin = self.d_cross if mode == "conservative" else self.d_cross / 2
        q_l = self.jsse_l.project_with_barrier(q_l_raw, swept_r, margin)
        q_r = self.jsse_r.project_with_barrier(q_r_raw, swept_l, margin)
        return q_l, q_r

    def decouple(self, role, state):
        for step in (CoupledRetreat, HoldAndSingleAbort,
                     ControlledPlace, CoordinatedEStop):
            if step.feasible(state, role):
                return step.execute(state)
        return CoordinatedEStop.execute(state)


class NeedInsightContract:
    """需求只是假设；只对 SNE 内需求行动；不确定则有界澄清。"""
    def __init__(self, goal_lib, cert_index, infer_model, clarifier, ledger,
                 tau_need, T_clar=3.0, N_q=2):
        self.goal_lib, self.cert_index = goal_lib, cert_index
        self.model, self.clarifier, self.ledger = infer_model, clarifier, ledger
        self.tau_need, self.T_clar, self.N_q = tau_need, T_clar, N_q

    def infer(self, obs, audio, ctx):
        h = self.model.infer(obs, audio, ctx)
        h.evidence = hash_evidence(obs, audio, ctx)
        self.ledger.append_need_hypothesis(h)
        return h

    def satisfiable(self, h, nrb, budget):
        if h.conf < self.tau_need(Rev(h)) or h.stale():
            return NeedCert(sat="NONE", reason="low_conf_or_stale")
        for g in sorted(h.G, key=h.pref):
            if g not in self.goal_lib:
                continue
            for pi in self.cert_index.plans(g, h.params):
                if pi.certified() and pi.respects(nrb) and pi.cost <= budget:
                    return NeedCert(g, pi.witness_hash, "FULL",
                                    coverage=pi.coverage, conf=h.conf,
                                    evidence=h.evidence, ttl=h.ttl)
        for g2 in h.G:                       # 安全局部履行
            for pi in self.cert_index.partial_plans(g2, h.params):
                if pi.certified() and pi.respects(nrb):
                    return NeedCert(g2, pi.witness_hash, "PARTIAL",
                                    coverage=pi.coverage, conf=h.conf,
                                    evidence=h.evidence, ttl=h.ttl)
        return NeedCert(sat="NONE", reason="not_in_SNE")

    def clarify(self, h):
        if self.clarifier.budget_exhausted(self.N_q, self.T_clar):
            return self.safe_partial_or_fallback(h)
        q = self.clarifier.best_question(h)   # 期望信息增益/成本
        if q is None:
            return self.safe_partial_or_fallback(h)
        return self.ask_and_update(h, q)

    def ask_and_update(self, h, q):
        answer = self.clarifier.ask(q)
        h2 = h.with_evidence(answer)
        self.ledger.append_need_update(h, q, answer, h2)
        return h2

    def safe_partial_or_fallback(self, h):
        cert = self.satisfiable(h, NRB_STRICT, B_task)
        if cert.sat == "PARTIAL":
            self.disclose("only_partial_fulfillment", cert)
            return cert
        self.disclose("fallback_canonical_need", h)
        return NeedCert(g=G0, sat="FULL", conf=1.0)   # v11 规范任务


class RoleCommitmentScheduler:
    """需求 -> 最少耦合角色 -> 成对证书 -> 承诺。"""
    def __init__(self, roles, bce, ledger, B_dec=2.0):
        self.roles, self.bce, self.ledger = roles, bce, ledger
        self.B_dec = B_dec

    def select_least_coupled(self, need_cert, state):
        if need_cert.sat == "NONE":
            return None
        for r in sorted(self.roles, key=lambda x: x.coupling):
            if not r.enter(state):
                continue
            if not self.bce.can_certify(r, need_cert.g, state):
                continue
            if not self.plan_exists(need_cert.g, r):
                continue
            return r                            # 最小耦合优先（P19）
        return None

    def commit(self, need_cert, state):
        r = self.select_least_coupled(need_cert, state)
        if r is None:
            self.ledger.append_commit_abstain(need_cert, "no_certified_role")
            return None
        pi = self.plan(need_cert.g, r)
        cert = self.bce.certify(r, pi, state)
        c = Commitment(need_cert.h, need_cert.g, r, pi, cert,
                       exit=r.egress, ver=self.version)
        self.ledger.append_commitment(c)
        return c

    def degrade(self, c, reason, state):
        nxt = D(c.r, state)
        self.ledger.append_degrade(c, nxt, reason)
        if nxt is None or nxt.coupling == 0:
            return "v11"                        # 严格回到 v11
        return self.commit_with_role(c.h, c.g, nxt, state)


def metricvoicegauge_round_12(M, s, obs, depth_or_pc, audio_stream, ...):
    ctx = mw_default_ctx()

    # ---- 感知侧：v11 全部 + BCE 相对/内力增量（契约预算内）----
    results = middleware.run_cycle(runners={
        "DA_ML":  lambda c: domain_adapter.update_and_measure(obs),
        "SPR":    lambda c: slam_risk.compute(M.slam_backend.get_latest_state()),
        "CAL_FI": lambda c: calib_fi.get_weights_kappa(),
        "OTL":    lambda c: online_learner.update_and_thresholds(c),
        "LM_MAP": lambda c: stf.update(obs.detections),
        "GSCF":   lambda c: gscf.update(obs.detections, depth_or_pc),
    }, ctx=ctx)
    ctx.delta_dom, ctx.tau_dom = results["DA_ML"], M.tau_dom
    bce.force_closure(obs.contacts_l, obs.contacts_r, obs.W, obs.mu, obs.load)

    # ---- NIC：需求假设 -> SNE -> 证书（不越权）----
    h = nic.infer(obs, audio_stream.latest(), ctx)
    need_cert = nic.satisfiable(h, nrb, budget)
    if need_cert.sat == "NONE":
        need_cert = nic.clarify(h)      # 有界；可能得到 PARTIAL 或 g_0
    n_need = int(need_cert.sat == "FULL")

    # ---- RCS：需求 -> 最少耦合角色 -> 承诺 ----
    if commitment is None or not commitment.valid(need_cert, live_obs):
        commitment = rcs.commit(need_cert, live_obs)
    if commitment is None:
        # n_need=0：只走 v11 单臂路径，行为等价 v11
        C, cert, claims, metrics, rewards = M.inherited_v11_path(ctx)
        distiller.step(cycle_idx, ctx)
        return C, cert, claims, metrics, rewards

    # ---- 5Hz 块生成：两臂 Ĉ⁺⁺ + 成对证书 Ĉ^bi ----
    if current_chunk is None or current_chunk.exhausted:
        current_chunk = chunker.generate_bimanual_chunk(
            ctx.state, ctx, stf, gscf, sra, nrb, bce, commitment)
        # 内部：先按 v11 独立认证两臂，再按 r 的相对/内力约束收紧；
        # 无有效 Ĉ^bi ⇒ 返回 None ⇒ 走 r_0 或 v11 单臂。

    # ---- 50Hz 每臂五检 + 500Hz 成对守卫 + 1kHz 互惠投影 ----
    verdict, target = chunker.midchunk_guard(
        current_chunk, k_exec, live_obs, stf, gscf, nrb,
        jsse_l, jsse_r, bce, commitment)

    if verdict == "continue":
        q_l, q_r = bce.reciprocal_project(
            current_chunk.q_l[k_exec], current_chunk.q_r[k_exec],
            live_obs.swept_l, live_obs.swept_r)
        execute_joint(q_l, q_r)
    elif verdict == "degrade":
        outcome = rcs.degrade(commitment, target, live_obs)
        if outcome == "v11":
            commitment = None
        current_chunk = None
    else:  # abort / coordinated estop
        bce.execute_abort(target)
        commitment = None
        current_chunk = None

    # ---- 需求漂移（1Hz/事件）：只触发任务层修订，不改安全阈值 ----
    if need_cert.sat == "FULL":
        delta = 1.0 - eval_goal(commitment.g, live_obs)
        if delta > tau_drift:
            nic.clarify(commitment.h)   # 修订走新承诺，不静默替换
            rcs.ledger.append_need_drift(commitment, delta)

    # ---- 1kHz JSSE 投影独立硬实时线程，两臂都不缺席 ----
    # q_cmd_i = jsse_i.project_with_barrier(ik_i(task_traj_i(t)), ...)

    # ---- v11 继承路径 + ID（安全守卫 φ^elig=false）----
    C, cert, claims, metrics, rewards = M.inherited_v11_path(ctx)
    distiller.step(cycle_idx, ctx)
    return C, cert, claims, metrics, rewards
```

## 4. 推导

**引理 103（成对证书的组合性）**
设每臂 Ĉ_i⁺⁺（i∈{L,R}）在 v11 引理 96 的假设下有效，且成对证书 Ĉ^bi 有效。则任一双臂执行轨迹 s(t) 满足 s(t)∈C_{q2,safe}。进一步，若 BCE 失效/关闭而 r←r_0，则只执行单臂 v11 计划，物理行为 ⊆ v11 可行集（支配性）。
证明：每臂轨迹∈C_{q,safe}^i（v11 引理 96）；相对证书保证 C_cross 中的相对位姿/内力/载荷/互障条件（定义 563–566）；C_{q2,safe}=乘积∩C_cross，故轨迹在内。BCE 失效时 r_0=INDEPENDENT 只调用 v11 每臂证书与中止，不产生新动作；单臂失效时对侧臂不得放宽自身证书（定义 566），故退化路径支配于 v11。∎

**引理 104（互惠屏障的冗余互不碰撞）**
设 V_j⊆V̂_j（V̂_j 为保守上界），臂 i 的投影保证 dist(link_i(q_i),V̂_j)≥d_cross。则 dist(L,R)≥d_cross。更强地，只要一条臂的屏障健康即可：因 R∈V_R⊆V̂_R，而 L 距 V̂_R≥d_cross，故 L 距 R≥d_cross。若两臂屏障均失效，1kHz 距离监视器在实测 d<d_cross 时触发双腕保持；监视器也失效 ⇒ 立即退出双臂（r←r_0），不再存在双臂互撞风险。
证明：集合包含 + 距离的单调性（V̂_j 变大则距离变小）；冗余性来自单侧条件已足够。∎

**引理 105（协调中止等价与降级终止）**
设每个 r 的 D_r 满足定义 568，且 v11 中止误差 ≤ε_fk。则：(i) 从任意承诺 c 出发反复应用 D_r，在 ≤depth(r)≤4 步内到达 r_0 或 v11 认证中止；(ii) 每步物理行为是上一步可行集的收缩（角色更松、约束更少但不新增动作）；(iii) 若到达 Q_abort^bi，则末端误差 ≤ε_fk、相对误差 ≤ε_rel^abort、物体态∈{HELD_SECURE,PLACED_SAFE}，故协调中止等价。
证明：格序有限且 D_r 严格下降，故终止；可行集收缩由 C_{q2,safe} 对更松角色只减约束/拆耦合；等价由三角不等式：‖FK(q_abort)−p*‖≤ε_fk，相对误差≤ε_rel^abort。∎

**引理 106（需求不越权与安全单调）**
对任意需求假设 h（包括错误/对抗/注入），NIC 只能输出 g 与 π∈Π_cert(g)，RCS 只能选 r∈R_cert；Adm(s) 与 h 无关（定义 574）。因此：健康双臂行为在 C_{q2,safe} 内；NIC/RCS/BCE 任一失效时行为退化为 v11 子集。错误 h 的最坏后果是选择一个「安全但非用户所需」的 g，不产生新危险态。
证明：定义 571 的 SNE 只允许 Π_cert 中的计划；定义 574 显式令 Adm 不含 h；失效路径由 Level-0a/0b/0c 定义。∎

**引理 107（SNE 健全性与澄清有界）**
若 Ĉ^need 给出 FULL，则存在 π∈Π_cert(g) 使 P_π(g)≥1−ε_need 且 π⊨NRB；若 NONE，则 G_lib 中无认证计划（是「本系统不能证」，不是「世界中不存在」）。Clarify 受 N_q≤2、T_clar≤3s 约束；无问题/超时 ⇒ PARTIAL 或 g_0，且被执行计划仍在 Π_cert。故澄清系统的任意行为不产生未认证动作。
证明：FULL/NONE 直接由定义 571 的查找与见证给出；Clarify 的预算与回退由定义 573 给出；PARTIAL/g_0 仍走 Π_cert。∎

**引理 108（承诺链的联合保守性）**
在 v11 引理 96 假设、定义 580 的度量与上述前提下，任一 ACTIVE 承诺 c 要么在 B_dec 内履行 g（沿途 Ĉ^bi 有效），要么沿角色格降级到 r_0/v11 中止；安全失败概率 ≤ v11 + ε_pair（ε_pair 为成对证书标定失败率，E631），需求失败被限制在 NeedFail/Utility，不进入 SafetyFail。
证明：组合引理 103 + 降级终止 105 + 不越权 106 + SNE 健全 107 + 并集界；ε_pair 只来自成对证书的标定/传感器误差，且失败时 r←r_0 回到 v11。∎

## 8. 本轮最大风险

**一句话**：需求洞察是整个系统中唯一无法被安全证书兜底的环节——一个高置信的错需求会让系统去严谨地证明「如何把一件不该做的事做对」，而双臂的高耦合会把这种目的层错误通过共享物体放大为物理后果；角色降级格只能在「已承诺的需求」内部收缩，无法自动发现承诺本身错了。
