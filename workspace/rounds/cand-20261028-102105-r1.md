# 第 11 轮 · SCORE-CARD：把官方评分表变成数据引擎，把泛化轴变成基准

## 0. 先给结论

这一轮把比赛从“32 个任务的平均成功率”改写成一个**四维张量**：

```
32 任务 × 5 泛化轴 × 每轴 2 次 × 2–5 个 rubric 步骤
```

首页榜单已可复核：MolmoAct/DexHacker **29.7% / 39.0 分**，WALLOSS 28.5% / 38.9，DreamZero 27.9% / 37.9，第 8 名 gr00t 20.5% / 28.1。榜首不到 30%，但**步骤分 39.0 与成功率 29.7% 不是同一套“每步等可靠”模型能同时解释的**：若每步独立同分布，29.7% 对应 q≈0.647、步骤分应≈45.3；实际只有 39.0。这个 6 分左右的缺口，说明头部模型的失败**集中在某些步骤/某些任务族**，而不是均匀地每步掉 35%。

所以本轮主线不是“再训一个更大的 VLA”，而是 **SCORE-CARD**：

1. **RUBRIC-MAP**：把 32 个公开的 100 分 rubric 变成 33k 条演示的步骤标签（步骤号、边界、完成度、可逆性）。
2. **AXIS-BENCH**：用官方 5 个泛化轴 + 8 个 robot / 192 个 session 做 **robot/session-held-out** 的离线与调试基准；只用于选 checkpoint，不冒充真机榜。
3. **HAT / REV-AUG**：用官方任务卡写出的**具体扰动方向**做几何增广（单应平移 + 动作重定向）和可逆步骤时间反演，造“位置/容器移动/人扰/状态回退”的训练信号。
4. **RUBRIC-EXEC**：推理时用步骤进度头做**步骤边界截断 + 边界处 best-of-K + 时间感知保分 + 回归检测重做**；保成功率，也保步骤分。

一句话押注：**在 33k 成功演示上，用官方 rubric 做密集监督、用官方扰动说明做规格化增广、用步骤感知的 best-of-K 保分——这是 30% 天花板下最可复现的撬点。**

## 1. 这轮怎么想：三个灵感词是一条链

### 1.1 基准测试：先问“分数到底怎么算”

官方规则（Feishu 中英文档，2026-10-28 可读）把评测写得很死：

- 32 个任务，每任务 **10 次**真机运行；5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰）**各 2 次**。
- 单次 **180s**；超时记失败，但**仍按执行情况计算步骤分并计入排名**。
- 排名先看**总平均成功率**；同分看**总平均步骤分**；再同分看**更早提交**。
- 另有**不计分的单任务测试通道**；多台测试机器人，需暴露 N 个连续端口 `8765..8765+N-1`；只允许**单模型**完成全部任务。
- 独立排行榜页仍显示 “Coming Soon”，但**首页榜单表已发布** 8 个模型；以首页表为准。

32 个任务卡（`https://unibot.unitree.com/tasks_v2/<slug>/info.json?v=2026-07`）公开了每个任务的 **100 分 rubric**，2–5 步，每步有中英文描述和分值。这是**公开的密集奖励**，但公开材料里没人把它当训练信号。先把这张表算清楚：

- 步骤数分布：**2 步 ×11、3 步 ×14、4 步 ×5、5 步 ×2**；难度：Easy 12 / Medium 12 / Hard 8。
- 首步平均 **35.47** 分，末步平均 **39.84** 分；完成前 1/2/3/4/5 步的平均累计分：**35.47 / 70.94 / 93.59 / 98.75 / 100**。
- 也就是说：**一个只会做前两步的模型，平均已经能拿 70.9 分**；步骤分的竞争在最后 1–2 步，而成功率的竞争在“全部步骤”。
- 统计功效：n=320 总体 SE≈2.56pp；每轴 n=64 SE≈5.73pp；每任务 n=10 SE≈14.49pp；每任务每轴 n=2 SE≈32.4pp。**单任务/单轴的小差异不可解读**，只能看大效应和任务族聚合。
- 轴分解：设 mild（位置/干扰物/背景）成功率 p_m，severe（未见物品/人扰）p_s，则 overall = **0.6 p_m + 0.4 p_s**。若 severe=0，mild 要 **50%** 才到 30%；若 severe=10%，mild 要 **43.3%**。**两轴是 30% 的门槛，不是加分项。**

榜单反推更有意思：29.7% 成功率 ↔ 均匀每步 q≈0.647；39.0 步骤分 ↔ 均匀每步 q≈0.593。两者差 5–6 分，说明头部模型不是“每步均匀 65%”，而是**某些步骤/任务族显著更差**。最可能的三种解释：

1. **任务族异质**：2 步任务（11/32）成功率高，3 步任务（14/32）拉低步骤分；
2. **步骤异质**：首步抓取难、后续放置相对容易（或反过来），导致“成功时拿满、失败时拿不到前段分”；
3. **步骤分公式不同**：官方可能不是“完成步骤分值累加”，而是别的归一化。

这三种解释可以用**单任务调试通道**一次区分：分别跑 2 步/3 步任务、记录失败发生在第几步、并用调试运行的步骤分反拟合官方公式。**这是本轮第一个可执行实验，不需要训练新模型。**

### 1.2 UniBot-V1：先问“数据到底是什么”

HF collection 32 个数据集，已解析 `meta/episodes` 与 `meta/tasks`：

- **33,276 episodes / 18,282,246 frames / 169.28h / 30fps / 4 相机**（`head_stereo_left/right`、`wrist_left/right`，480×640）。
- **192 sessions、8 个 robot ID、80 个采集日、2026-02-05 至 2026-06-25**；每任务 3–10 sessions、2–6 robots。
- 每任务 **5 条英文复述指令**（`tasks.parquet` 里用 `@` 拼接，共 160 条）；但官方 5 个评测轴**不含语言复述**——复述只做廉价增广，不做主轴。
- 所有 episode **<80s**（最长 OrganizeTools 79.9s），远低于 180s；超时主要是策略卡住，不是任务本身长。
- 数据含部署 API 不暴露的特权通道：`lower_body`、torso 系 EE、`state_torso`、`state_d435`、`recomputed_ee_valid`；部署只给 base 系 EE、arm joints、grippers、4 相机、language。
- `action.gripper_controls` 是遥操作通道，`squeeze` 随夹爪开合运动变化，**不是力**；第 10 轮已剪，本轮继续不用。
- **成功演示 only**；未见物品变体在任务卡里写“缺少/不同”，人扰写“过程中移动/拿走/复原”；**没有失败恢复标签**。

上一轮口径说“5 个 robot”，本轮逐 episode 重算后是 **8 个**：8520（27 任务 / 11,709 eps）、6150（24 / 5,609）、8343（15 / 4,487）、8021（11 / 4,485）、6559（10 / 4,428）、7365（5 / 1,288）、5783（1 / 975）、8730（1 / 295）。更重要的是：**13/32 个任务被单一 robot 占 >80%**（PlugCharger、ToolboxStorage 95% 是 6150；StoreCups 95% 是 5783；FoldTowel 95% 是 8520；OrganizeBookshelf 95% 是 8343）。**随机划分会泄漏 robot 身份**，验证集会被高估；必须做 robot/session-held-out。

还有一个被忽略的资产：每个数据集的 `meta/info.json` 带 **`camera_params`**。以 HangCup 为例，头部双目已校正，`fx≈282.37, fy≈282.75, cx≈311.53, cy≈256.63`，基线 `T≈58.25mm`；腕部 `fx≈436.4`。这意味着 HAT 不需要猜内参，**可以直接用官方标定做平面单应**。

### 1.3 数据集构建：先问“缺的那一块能不能自己造”

官方任务卡把 5 个轴写成了**具体扰动方向**，例如：

- HangCup：“杯子向后 / 杯子向右”；
- PlugCharger：“抓插头前进行移动 / 将插头拔起”；
- OrganizeBookshelf：“抓到书后挪动架子”；
- ZipUp：“拉上拉链之后拉开”；
- FoldTowel：“将叠完的毛巾翻开”；
- ConveyorSorting：“可乐快到了然后放回传送带起点”；
- Unlock：“中途把锁拿走”。

这不是隐私，这是**公开的扰动规格**。把它解析成 perturbation DSL，就能造出**方向匹配**的增广，而不是随机平移：

| 类型 | 例子 | 可合成的信号 |
|---|---|---|
| 抓取前目标平移 | 杯子后/右、水果前/右、试管左/右 | HAT：头部图像单应 + 未来 EE 轨迹平移 |
| 抓取后容器/架子平移 | 书架、绿色盒子、网口、底座 | HAT：抓取后的 place 段平移 + 头部图像平移 |
| 中途移除/拿走 | 锁、第二个碗、手机壳、便签 | 物体 mask/移除 + 重规划/放弃 |
| 状态回退 | 拉链拉开、盖子拧回、毛巾翻开、文具盒打开 | REV-AUG：可逆步骤时间反演 + 恢复策略 |
| 时序/传送带 | 可乐/薯片快到了放回起点 | 时间重参数化 + 重抓 |

HAT 的几何：桌面近似平面，3D 平移 δ 诱导单应 `H = K (I + δ nᵀ / d) K⁻¹`；用双目深度/RANSAC 估平面，用官方 K；把头部图像 warp，未来 EE 动作 `a' = a + [δ,0]`；腕部相机在“机器人跟随平移轨迹”时相对几何不变，可保持原图或只做短时混合。中期扰动插入 5–10 帧 **re-approach bridge**，让动作从当前状态平滑接到平移后的轨迹。REV-AUG 则把可逆步骤的子轨迹时间反演，得到“状态回退”负样本，训练进度方向分类器和恢复策略。两者都**不需要新机器人时间**。

### 1.4 三个灵感词合起来

- **基准测试**告诉我们：分数是 rubric 张量，不是单一 success；步骤分同分决胜，且 n=2/轴不可解读。
- **UniBot-V1** 告诉我们：数据有 8 robot / 192 session / 80 日 / 5 复述，但 severe 两轴没有标签；随机划分会泄漏 robot；相机有官方标定。
- **数据集构建**告诉我们：官方扰动说明是公开规格，可以用 HAT/REV-AUG 造出方向匹配的恢复数据；rubric 是公开密集奖励，可以监督步骤进度。

## 3. 为什么不是其他路线

- **不是“再训更大的 VLA”**：33k 数据 + 少卡，6B 已接近上限；榜单头部大概率就是开源 VLA 微调，差距在数据/评测/恢复，不在参数量。参数量翻倍对 severe 轴的边际收益最低。
- **不是“语言复述增广”**：官方轴不含语言；5 条复述已够，边际收益低。复述只做低成本鲁棒性，不占主轴。
- **不是“力/触觉”**：API 不暴露；第 10 轮已剪。`gripper_controls` 不是力。
- **不是“接触强度推难度”**：第 10 轮已证伪（占位数据下相关性弱）；本轮用 rubric 步骤分，不用接触代理当监督。
- **不是“完整世界模型/MPC”**：延迟和单模型合规风险；用一步 lookahead 的 progress head 足够。
- **不是“per-task per-axis 调参”**：n=2，SE 32pp；必然过拟合。
- **不是“重测试时搜索”**：规则不允许/会记录交互质量；只做训练时增广和推理时保分。

## 4. SCORE-CARD：四层，一个 checkpoint

**L1 RUBRIC-MAP（步骤标签）**

- 把 32 个 rubric 解析成 schema：`task_id, steps[{id, desc, score, verb, object, target, cue, reversible}], dag`。默认链式；PackBag、ToolboxStorage、OrganizeStationery 等手工标 DAG（步骤可交换/累积）。
- 用每任务 5 个官方示例视频 + 前 5 条演示标步骤边界（160 段），两人标注，要求 Cohen's κ≥0.7、边界 MAE≤0.5s。
- 用冻结 DINOv2/CLIP 特征 + proprio + gripper + EE 训一个轻量时序模型（TCN/Transformer+CRF），输出每步完成概率与边界；在 160 段上监督，再在 33k 上自训练（置信度阈值 + 时序平滑）。
- 标签用于：步骤平衡采样、边界截断、进度辅助损失、步骤感知评估。**不修改官方数据，只新增 annotation 层。**

**L2 AXIS-BENCH（轴基准）**

- 32×5×2 = 320 个单元；训练/验证按 **session** 与 **robot** 分组，绝不随机按帧划分。
- 5 轴的数据来源：位置=HAT 平移或不同 session 的初始位姿；干扰物=官方干扰物 mask 粘贴；背景=不同日期/场景替换；未见物品=物体外观/几何替换（任务卡写“缺少”的变体）；人扰=HAT 中期平移 + REV-AUG 状态回退 + 合成手遮挡。
- 指标：步骤完成率、成功率代理（全步骤完成）、步骤分、平移等变误差、恢复时间、动作平滑度、碰撞代理（EE z / 工作空间）、延迟。
- 校准：用单任务调试通道 2 任务×10 次，拟合离线→真机的线性/秩相关；**只用于选 checkpoint，不对外宣称榜单**。
- 关键：**13/32 任务单 robot >80%**，所以同时报告 random-split 与 robot-held-out 的差距；差距大就说明模型学了 robot shortcut。

**L3 数据引擎（HAT / REV-AUG / 外观）**

- HAT：官方 K + 双目深度/RANSAC 平面 + 单应 warp + EE 动作平移 + re-approach bridge；有效性门控：单应误差、抓取投影、IK、工作空间、碰撞、视觉合理性。
- REV-AUG：可逆步骤（拉链、拧盖、折叠、开合、堆叠）时间反演；训练进度方向分类器 + 恢复策略；只对可逆步骤启用。
- 外观/背景/干扰物：分割 + 粘贴/替换 + 一致性损失；不用新标签。
- 配对损失：`L_eq = ||π(o_shift) − T_δ π(o)||²`（HAT 对，只对 EE/arm 维度、只用头部相机）；`L_inv = ||π(o_aug) − π(o)||²`（外观/背景/干扰物）。训练时加权 ramp，干净数据≥50%，防止坍缩。

**L4 RUBRIC-EXEC（执行保分）**

- 进度头：每步 `p_k = P(step k complete | o_t)`，单调校准；边界头预测下一步开始。
- 边界处 best-of-K（K=2）：用 `Σ s_k · p_k(chunk)` 打分，选期望步骤分最高的 chunk；平票选更短/更平滑。
- 时间感知：剩余时间 < 下一步估计时间 + 安全裕度时，进入“保当前步骤”的安全保持/回撤，不硬冲导致回退。
- 回归检测：若 `p_k` 下降超过阈值，判定状态被扰动/回退，触发 re-approach 或重做当前步骤。
- 低层保留第 10 轮 FACT-VLA 的 FACTOR/CPT/CAC：接触相位、夹爪滞止、柔顺；**不重复第 10 轮**，只把“接触相位”升级成“rubric 步骤相位”。

## 5. 与第 10 轮的关系：保留、升级、剪枝

- **保留**：FACTOR 无传感器接触代理、CPT 相位化 BC、CAC 柔顺、EGP 证据门控。
- **升级**：接触相位 → rubric 步骤相位；接触加权 → 步骤平衡采样；尾段安全 → 最后一步保分；证据门控 → 轴/任务分层分配。
- **剪枝**：力/触觉、接触强度→难度、完整世界模型、重测试时搜索、语言复述主轴、`gripper_controls` 当力。
- **新增**：rubric 标签、HAT、REV-AUG、AXIS-BENCH、等变/不变损失、步骤感知 best-of-K、robot-held-out 诊断。

## 7. 风险与合规

- **单模型**：所有头共享一个 checkpoint；HAT/REV 离线；推理不调用第二模型；best-of-K 只采样同一模型。
- **规则**：不硬编码任务/物体；不用测试时搜索；不读评测状态；N ports 状态隔离；`meta.token` 每次带。
- **数据**：只用官方公开数据；43+ 个非挑战赛 G1 Dex1 数据集默认 OFF，规则不明。

- 严格 LORO 只对覆盖 ≥2 robot 且每 robot ≥100 eps 的任务可行；对 6150 占 95% 的 PlugCharger/Toolbox，留出 6150 后只剩 50 eps 的 8520，训练不足，只能做 **cross-robot zero-shot 诊断**，不能当训练验证。
- 5783（StoreCups）与 8730（StorePaddle）是单任务 robot，适合做 **cross-robot 泛化测试**；但 StoreCups 留出 5783 后只剩 50 eps 的 8520，样本极少，结论要谨慎。
- 6150 在多数任务约 50 eps，但在 PlugCharger/ToolboxStorage 是 95% 主力（972/1014），像是后加入的“统一采集波”；若测试机器人接近 6150，训练集对它的覆盖可能不足，需在 debug 中验证。

部署 obs（README v2）：

| key | shape | 说明 |

| `observation.state.left_ee_pose_gripper_base/right...` | [6] float32 | base 系 xyz+rpy |
| `observation.state.left_gripper/right_gripper` | [1] float32 | 夹爪开合 |
| `observation.state.lower_body` | [15] float32 | 可选；声明才发送 |

部署 action：

| key | shape | 控制空间 | 说明 |
|---|---|---|---|
| `meta.token` | str | shared | 每次 `get_action` 必带 |
| `action.left_gripper/right_gripper` | [1] | shared | 夹爪目标 |
| `action.pivot` | [7] | shared | 下肢/底盘目标；桌面任务多为保持 |
| `action.left_arm/right_arm` | [7] | `joint` | 关节目标 |
| `action.left_ee_pose_gripper_base/right...` | [6] | `ee` | base 系 EE 目标 |

关键契约：

- `control_space` 只能是 `"joint"` 或 `"ee"`，二者互斥；**本轮选 `ee`**，因为 HAT 的动作平移是直接的 `a' = a + [δ,0]`；`joint` 需要 IK 才能平移。若 debug 发现 `ee` 的 IK 跟踪误差大/奇异点多，回退 `joint` + IK-HAT。
- `obs_delta_indices` 的**键决定哪些 obs 被发送**，值是该键的逐帧偏移（≤0）；只声明最小子集：4 图像 `[0]`、arm `[-4,-2,0]` 或 `[-2,0]`、EE `[-2,0]`、gripper `[-4,-2,0]`、language `[0]`。
- `image_resize` 用 `[height,width]`，官方用 `cv2.resize`；4 相机 **240×320** 是带宽/延迟的合理起点；native 480×640 在 N ports 下带宽过高。
- `action_chunk_size` T_a ≥1；建议 8–16；返回形状 `(T_a, …)`；每个 chunk 执行完再请求。
- token 必须在 `metadata` 和**每次** `meta.token` 中一致；缺失/不匹配直接拒绝。
- N ports：每个端口一个 `PolicyService`；模型可共享，但**进度状态、历史、rubric 进度必须按端口隔离**；推理服务要线程安全/批处理。
- §6 会记录延迟、波动、动作规律性；best-of-K 只在步骤边界，避免每帧翻倍。

**数据集与部署的差异**：

- 数据 action 有 `lower_body` [15]、`gripper_controls` [4]、`base_command` [4]、torso/d435 EE；部署只要求 `pivot` [7] + arm/EE + gripper。训练时只监督部署存在的键；`lower_body`/`gripper_controls`/`base_command`/torso EE 不作为推理输入。
- 数据 obs 有 `state_torso`、`state_d435`、torso 系 EE、`recomputed_ee_valid`；部署不暴露。用 base 系 EE，不要依赖 torso 系。
- 数据 `action.pivot` 有 7 维（`vx,vy,angle_z,pivot_3..5,height`）；桌面任务大多为零/保持，按任务统计后再决定是否监督。
- 数据夹爪 Hand Convention：开源 5.5 → 闭合 0.0；数据实际约 0–4.5；部署 `action.left_gripper` 是目标开合，训练时保持同一约定，不要混用归一化。

### 1.7 特权通道与 `gripper_controls`

数据含部署不暴露的通道：`observation.state.lower_body`（15）、`left_leg/right_leg`（6+6）、`left_ee_pose_gripper_torso/right...`（6+6）、`state_torso`（6）、`state_d435`（6）、`recomputed_ee_valid`（1）；action 含 `lower_body`（15）、`left_leg/right_leg`（6+6）、`gripper_controls`（4）、`base_command`（4）、torso/d435 EE（6+6）、`waist_action_joint`（3）。

- **推理时全部丢弃**；训练时最多用作辅助监督/诊断，不能作为部署输入。
- `action.gripper_controls` = `[left_trigger, left_squeeze, right_trigger, right_squeeze]`；HangCup 张开时常见 `[10,0,10,0]`，`squeeze` 随夹爪开合运动变化；**不是力矩/力**，不能当力标签。第 10 轮已剪，本轮继续不用。
- `camera_params` 是资产：HangCup 头部双目已校正，`K_left=[[282.369,0,311.525],[0,282.752,256.628],[0,0,1]]`，`K_right=[[281.874,0,329.958],[0,282.319,249.512],[0,0,1]]`，基线 `T≈[-58.25,-0.17,0.58]mm`；腕部 `K≈[[436.4,0,323.9],[0,435.9,242.9],[0,0,1]]`（左右略有差异），640×480，腕部有 inverse Brown-Conrady 畸变。HAT 用每数据集 `meta/info.json` 的 `camera_params`，不要硬编码 HangCup 的值。

## 2. 关键分析

### 2.1 Rubric 分数曲线

| 指标 | 数值 |
|---|---|
| 2/3/4/5 步任务数 | 11 / 14 / 5 / 2 |
| Easy/Medium/Hard | 12 / 12 / 8 |
| 首步平均 | 35.47 |
| 末步平均 | 39.84 |
| 完成前 1/2/3/4/5 步平均累计 | 35.47 / 70.94 / 93.59 / 98.75 / 100 |
| 2 步任务分值 | 50/50 |
| 3 步任务分值 | 30/30/40（14 个全部） |
| 4 步任务分值 | 25/25/25/25（5 个全部） |
| 5 步任务分值 | 20×5（2 个全部） |

**直接含义**：

- 步骤分有很高的“保底”：只完成前两步，平均 70.94 分；只完成第一步，平均 35.47 分。
- 3 步任务是主体（14/32），且末步 40 分；成功率的乘积结构使 3 步任务成为 success 的主要拖累。
- 4/5 步任务只有 7 个，但每个步骤分低（20–25），且乘积衰减快；它们对 success 的拖累最大，对 step score 的绝对贡献较小。
- 2 步任务（11 个）是 success 的“高杠杆任务族”：同样 q 下，2 步成功率 q² 远高于 3 步 q³。若模型在 2 步任务上强，会把 overall success 拉高，但 step score 未必同步——这正是榜单 29.7%/39.0 缺口的候选解释。

### 2.2 榜单反推：均匀 q 被拒绝

用精确 rubric 计算：

- q=0.60 → 24.3% / 39.7
- q=0.647 → 29.7% / 45.3
- q=0.593 → 23.7% / 39.0

榜首 (29.7, 39.0) 落在“success 需要 q≈0.647、score 需要 q≈0.593”之间；**均匀每步可靠性无法同时拟合**。几何 profile `q_i = q r^{i-1}` 的一个拟合是 q≈0.533、r≈1.215（后步更可靠；5 步尾部 q>1，参数化失效，仅作方向性参考）。更直观的二维扫描：

| q1（首步） | q_rest（其余步） | 平均成功率 | 平均步骤分 |
|---|---|---|---|
| 0.50 | 0.65 | 23.1% | 34.9 |
| 0.55 | 0.65 | 25.4% | 38.4 |
| 0.55 | 0.70 | 28.8% | 40.4 |
| 0.60 | 0.65 | 27.7% | 41.8 |
| 0.60 | 0.70 | 31.4% | 44.1 |
| 0.65 | 0.65 | 30.1% | 45.3 |

**两种简化剖面都能靠近榜首**：几何 profile q≈0.53、r≈1.22（首步 0.53、第 2 步 0.65、第 3 步 0.79…）拟合 29.7%/39.0；两水平模型 q1≈0.55、q_rest≈0.70 给出 28.8%/40.4（success 略低、score 略高）。**共同方向是首步比后续步低 10–15pp**；这不是唯一解，但比“每步均匀 0.65”更符合数据。**可检验预测**：在调试通道中，首步（抓取/接近）失败率应显著高于后续步；若相反，则缺口来自任务族或步骤分公式。

### 2.3 步骤杠杆：首步是最大杠杆

在 q=0.6 下，把 32 个任务的期望步骤分贡献拆开（sum over tasks）：

| 步骤 | 期望贡献 | +0.05 的边际收益 |
|---|---:|---:|
| 第 1 步 | **681.0** | **56.8** |
| 第 2 步 | 408.6 | 34.0 |
| 第 3 步 | 156.6 | 13.0 |
| 第 4 步 | 21.4 | 1.8 |
| 第 5 步 | 3.1 | 0.3 |

原因：第 1 步的前缀概率是 1，不被任何前置步骤折扣；第 3 步的分值虽高（40），但要乘 `q1·q2`；第 5 步乘 `q1..q4`。所以：

- **步骤分**：首步是最大杠杆；末步的边际收益很小。
- **成功率**：均匀 q 下各步弹性相同；若首步 q1 更低，首步的弹性最大。首步是“成功率的 gate”。
- **场景**：uniform 0.6 → 39.7/24.3%；首步 1.0、其余 0.6 → **66.2/40.6%**；首步 0.6、其余 0.7 → 44.1/31.4%。**修首步的收益远大于修末步**。
- 但这不意味着“只练抓取”：首步的定义因任务而异（HangCup 是抓杯把，PlugCharger 是抓插排，FoldTowel 是挥正毛巾，Toolbox 是收纳 2 个工具）。RUBRIC-MAP 必须按任务解析首步语义，不能统一当“grasp”。

**策略含义**：先用调试通道测每步成功率；若首步 <0.65，优先修首步（接近/抓取/夹爪闭合/物体定位）；若首步 ≥0.75 而 success 仍低，再修末步（插入/挂/盖/拉链）。不要盲目追“最后一步”。

### 2.4 统计功效

| 单元 | n | 成功率 SE | 能检测的最小差异（约 2SE） |
|---|---:|---:|---:|
| 总体 | 320 | 2.56pp | ~5pp |
| 每泛化轴 | 64 | 5.73pp | ~11pp |
| 每任务 | 10 | 14.49pp | ~29pp |
| 每任务每轴 | 2 | 32.4pp | ~65pp |

**结论**：

- 只能对**总体**和**任务族/轴聚合**下结论；单任务/单轴（n=2）的差异基本是噪声。
- 离线 AXIS-BENCH 必须用远大于 2 的样本；真机调试每任务 10 次也只能看大效应（≥20–30pp）。
- 排行榜 8 个模型的 1–2pp 差异在 n=320 下约 0.4–0.8 SE，不能过度解读；但 5pp 以上（约 2SE）有意义。
- 消融至少 3 seeds；报告 95%CI；不要用单次全量提交的排名当模型优劣的唯一证据。

### 2.5 轴分解

`overall = 0.6 p_mild + 0.4 p_severe`（mild=位置/干扰物/背景；severe=未见物品/人扰）。

| severe p_s | 需要 mild p_m 才能到 30% | 需要 mild p_m 才能到 25% |
|---:|---:|---:|
| 0% | 50.0% | 41.7% |
| 5% | 46.7% | 38.3% |
| 10% | 43.3% | 35.0% |
| 15% | 40.0% | 31.7% |
| 20% | 36.7% | 28.3% |
| 25% | 33.3% | 25.0% |

**边际收益**：mild +10pp → overall +6pp；severe +10pp → overall +4pp。mild 的单位 pp 收益更高，但 severe 的 headroom 更大（0→20 比 50→70 容易）。**先补 severe 的 0→10，再把 mild 从 45 推到 55**，比只刷 mild 更现实。

### 2.6 Robot shortcut / 数据泄漏

- 13/32 任务单 robot >80%；随机划分会让同一 robot 的同一场景同时出现在 train/val，验证 success 被高估。
- 正确协议：**session-grouped**（同一 robot-date 的 session 不跨 split）+ **robot-held-out**（对覆盖足够的任务留出一个 robot）。
- 严格 LORO 的可行任务：8520/6150/8343/8021/6559 覆盖 ≥10 任务；7365 只有 5 任务；5783/8730 单任务。对 6150 占 95% 的 PlugCharger/Toolbox，留出 6150 后训练样本只剩 50，不能做训练验证，只能做 zero-shot 诊断。
- 报告时必须同时给 **random-split** 与 **grouped-split** 的数字；差距 >5pp 就提示模型吃了 robot/scene shortcut，真机泛化会被高估。
- 一个合理推测：榜单头部集中在 20–30%，部分原因是大家在同一批 8 robot 数据上微调；随机划分的 offline 数字可能很好看，但真机换 robot/场景就掉。

### 2.7 头部方案假设与瓶颈

**声明**：榜单只给模型/用户名称，没有方法披露；以下是基于名称与公开模型的假设，不是官方事实。

| 排名 | 模型/用户 | 可能路线 | 可能瓶颈 |
|---|---|---|---|
| 1 | MolmoAct/DexHacker | MolmoAct 系 VLA 微调；EE/action chunk；4 相机 | 未见物品、人扰、首步抓取 |
| 2 | WALLOSS/Generalist Robotics | WALL-OSS 系 3B VLA；数据管线强 | 与榜首差 1.2pp/0.1 分；步骤分接近，可能在末步/部分完成 |
| 3 | DreamZero/World Model Lab | 世界模型/预测式策略 | 步骤分 37.9 低于 WALLOSS 38.9，success 也低；部分完成多 |
| 4 | spirit/VLAGO | VLA + 可能语言/推理 | 25.9%/34.4，差距 3.8pp/4.6 分 |
| 5 | DM/Embodied AI Institute | 扩散/流匹配策略 | 23.5%/31.7 |
| 6 | PI/RoboReasoner | PI 系 + 推理 | 22.8%/30.6 |
| 7 | GigaBrain/xembody | GigaBrain 系 VLA | 22.6%/29.5 |
| 8 | gr00t/Humanoid Dynamics | GR00T N1.5 系 | 20.5%/28.1 |

**共同瓶颈**（假设）：

1. **首步抓取/接近**：rubric 首步均值 35.47，且是后续步骤的 gate；榜单反推首步 q≈0.53–0.55。
2. **未见物品**：23/32 任务卡明确写“缺少不同物体”；训练集没有这些变体；外观/几何 OOD。
3. **人扰恢复**：30/32 任务卡有“移动/拿走/复原”备注；训练集是成功演示，没有恢复标签；模型遇到扰动后不会重规划。
4. **任务族异质**：2 步任务 vs 3 步任务；随机划分掩盖了 robot/scene shortcut。
5. **步骤分**：头部 39.0 接近“只完成首步”的 35.47 + 少量，与“大量运行只拿到首步分”的画像一致；但仅凭聚合数不能证明，需调试通道按步记录。

**头部可能没做的**（公开材料未显示，作为差异化假设）：

- 没有把 rubric 当步骤级监督；只优化 success。
- 没有用官方扰动方向做**规格化**增广；可能用随机平移/颜色抖动。
- 没有 robot-held-out 验证；可能被 random split 高估。
- 没有用双目几何做 HAT；可能只用 2D 增广。
- 没有训练状态回退/恢复；人扰轴靠 prompt/重试。
- 没有步骤感知 best-of-K；只返回单个 chunk。

**结论**：头部不是“不可追赶的 2× 差距”，而是同一数据/同一基座上的 1.2–9.2pp 差异；**数据引擎和评测协议**是正交的撬点。目标不是立刻超过 29.7%，而是先到 20–25% 并把步骤分从 39 推到 45+，再冲 30%。

## 3. 方法

### 3.1 总览

```
4 相机 + proprio + language
        │
        ▼
[感知/编码] ──► [FACTOR 接触代理] ──► [RUBRIC-MAP 步骤进度]
        │                                   │
        ▼                                   ▼
[动作专家 π (flow/diffusion)] ◄── [RUBRIC-EXEC 边界/best-of-K/保分]
        │
        ▼
EE 动作 chunk (T_a×6+6+2+7) + meta.token
```

**训练时**：RUBRIC-MAP 标签 + HAT/REV-AUG/外观增广 + 等变/不变损失。
**推理时**：单 checkpoint；进度头/边界头/动作专家共享；best-of-K 只在边界；N ports 状态隔离。
**低层**：第 10 轮 FACTOR/CPT/CAC 的接触相位/夹爪滞止/柔顺；不重复。

### 3.2 RUBRIC-MAP

**Schema**：

```json
{
  "task_id": "T01",
  "slug": "hang_the_cup",
  "steps": [
    {"id": 0, "zh": "抓住杯把", "en": "Grab the cup handle", "score": 50,
     "verb": "grasp", "object": "cup_handle", "target": null,
     "cue": "gripper_closed_on_handle", "reversible": false},
    {"id": 1, "zh": "挂到杯架标记位置上", "en": "Hang it on the marked spot",
     "score": 50, "verb": "hang", "object": "cup", "target": "rack_mark",
     "cue": "cup_hanging_stable", "reversible": false}
  ],
  "dag": [[0,1]],
  "total": 100
}
```

**标注**：

1. 解析 32 个 `info.json`：步骤、分值、中英文、`generalization` 备注；校验分值 sum=100、步数 2–5。
2. 每任务取 5 个官方示例视频 + 前 5 条演示（共 160 段），标注每步的 start/end；两人独立标，分歧仲裁；目标 κ≥0.7、边界 MAE≤0.5s。
3. 对 DAG 任务（PackBag/Toolbox/OrganizeStationery）标“可交换/累积”关系；其余默认链式。
4. 训轻量时序模型：冻结 DINOv2/CLIP 图像特征（4 相机可只取头部+腕部各 1）+ proprio（arm/EE/gripper）+ 语言嵌入；2 层 Transformer/TCN + CRF；输出每步完成概率 `p_k(t)` 和边界 `b_k(t)`。
5. 自训练：在 33k 上用高置信度伪标签 + 时序平滑（Viterbi）扩展；每任务保留 ≥10% 人工验证。
6. 验证：留出 10 episodes/task 的人工标签；报告每步 precision/recall、边界 MAE、κ；不通过则只用 160 段监督 + 规则相位。

**用途**：

- 步骤平衡采样：`w_t = min(1/P(step), cap)`，保证每步 ≥10% batch；对首步额外加权（首步是最大杠杆）。
- 边界截断：动作 chunk 在步骤边界截断/重规划；避免“跨步平均”把动作抹平。
- 进度辅助损失：`L_step = BCE(p_k, y_k) + λ_b BCE(b_k, y_b)`；只在有标签/高置信样本上。
- 步骤感知评估：每步成功率、每步失败类型、每任务首步/末步瓶颈。
- 恢复触发：`p_k` 下降 >τ 判定回退；结合 REV-AUG 方向分类器。

**伪代码**：

```python
def rubric_map(episode, model, conf=0.9):
    feats = frozen_encoder(episode.images, episode.proprio, episode.lang)
    p_step, p_bound = model(feats)          # (T,K), (T,K)
    p_step = viterbi_smooth(p_step)         # monotone / DAG constraints
    labels = {}
    for k in range(K):
        mask = p_step[:,k] > conf
        labels[k] = mask
    return p_step, p_bound, labels
```

**不做什么**：不把 rubric 当硬编码控制器；不要求每帧都有标签；不把步骤号当唯一条件（用每步完成概率 + DAG）。

### 3.3 AXIS-BENCH

**切分**：

- `train`: 80% sessions per task，按 robot 分层；`val`: 10%；`test`: 10%。同一 session 不跨 split。
- `robot-held-out`: 对每个任务，留出覆盖 ≥10% 且 ≥100 eps 的 robot；若留出后训练 <100 eps，则只做 zero-shot 诊断，不进入主表。
- `date-held-out`: 留出最后 2 周（2026-06-10–06-25）的 session，模拟时间漂移。
- `task-family`: 2 步 vs 3 步 vs 4/5 步；Easy/Medium/Hard；按任务族聚合，不报单任务。

**5 轴**：

| 轴 | 数据来源 | 合成方法 | 指标 |
|---|---|---|---|
| 位置 | 不同 session 初始位姿；HAT 平移 | 头部单应 + EE 平移；δ 2–10cm | 步骤完成、成功率代理、平移等变误差 |
| 干扰物 | 官方备注的干扰物；分割/粘贴 | 桌面空闲区粘贴物体 mask；不遮挡目标 | 步骤完成、误抓率 |
| 背景 | 不同日期/场景；分割替换 | 桌面/背景替换；保持光照/阴影 | 步骤完成、颜色/纹理不变性 |
| 未见物品 | 任务卡“缺少/不同”的变体；3D/图像替换 | 物体外观/几何替换；优先用同任务其他实例 | 步骤完成、首步抓取率 |
| 人扰 | 官方备注的移动/拿走/复原；HAT+REV | 中期平移 + re-approach bridge；时间反演；合成手遮挡 | 恢复时间、恢复后步骤完成、回退检测 |

**指标**：

- 主：**步骤完成率**（RUBRIC-MAP 分类器）、**成功率代理**（全步骤完成）、**步骤分**（Σ s_k · 完成）。
- 辅：平移等变误差 `||π(o_shift) − T_δ π(o)||`、恢复时间（从扰动到重新 progress）、动作平滑度（jerk）、碰撞代理（EE z/工作空间）、延迟 p50/p99。
- 校准：单任务调试 2 任务×10 次；拟合 offline→real 的线性/秩相关；报告 Spearman ρ；若 ρ<0.5，AXIS-BENCH 只用于相对排序，不用于绝对预测。

**协议**：

- 3 seeds；报告 mean±95%CI；paired bootstrap；不报单任务/单轴小差异。
- 每个 axis 至少 2 个任务族（2 步 + 3 步）；severe 轴至少 2 个任务族。
- 公开/内部两版：内部版含官方备注的精确方向；公开版只给协议，不给测试答案（避免污染）。

**为什么不是普通 offline benchmark**：普通 offline 用 action MSE/成功率分类器，和真机 success 相关性弱；AXIS-BENCH 用**官方 rubric 步骤**和**官方轴**，并用调试通道校准，目标是把 offline 变成**checkpoint 选择工具**，不是替代真机。

### 3.4 HAT（Homography-Augmented Trajectories）

**几何**：

- 桌面近似平面 `nᵀX = d`；3D 平移 δ（平行于桌面）诱导 `H = K (I + δ nᵀ / d) K⁻¹`（δ 为场景平移时符号取反；以重投影误差为准）。
- 头部双目已校正：用 `camera_params.head_stereo.camera_matrix_left` 的 K；用左右图做 SGBM/RAFT-Stereo 得深度，RANSAC 拟合桌面平面；或用跨 episode 特征匹配（LoFTR/SIFT+RANSAC）直接估 H。
- 物体 3D 位置：在抓取帧用双目深度 + 抓取点像素 → 3D；δ = 目标位置 − 原位置；或直接指定 δ（2–10cm）并检查工作空间。
- 动作重定向：`a'_{t≥t0} = a_t + [δ, 0]`（EE xyz 平移，rpy 不变；夹爪/pivot 不变）。对 `joint` 控制，用 IK 求平移后的关节；若 IK 失败则拒绝。
- 中期扰动：保留 `t<t0` 原动作；插入 5–10 帧 minimum-jerk bridge 从当前 EE 到 `a_{t0}+δ`；再执行平移后的未来动作；头部图像从 `t0` 起 warp；腕部图像在“物体已在夹爪”时保持原图（相对几何不变），在“抓取前”时可选 warp 或丢弃。
- 容器移动（抓取后）：对 place 段平移 δ；物体在夹爪，腕部不变；头部 warp 显示容器新位置。
- 人扰（中期平移）：同中期扰动；若人手遮挡，叠加合成手 mask 或直接丢弃被遮挡帧（训练时）。

**有效性门控**：

| 门 | 检查 | 阈值 | 不通过 |
|---|---|---|---|
| H0 | 单应重投影误差 | <2px（100 对） | 退 2D 平移/特征 warp |
| H1 | 平移后抓取点投影 vs 物体 mask 质心 | <5px | 拒绝该样本 |
| H2 | IK 成功率/关节限位/工作空间 | >95%；EE z > 桌面+2cm | 拒绝/缩 δ |
| H3 | 碰撞代理（EE 轨迹 vs 桌面/架子） | 无穿透 | 拒绝 |
| H4 | 视觉合理性（腕部/阴影/遮挡） | 人工抽检 50 对 ≥90% | 缩 δ/只做头部 |
| H5 | 真机 2 任务×10 次 | 恢复提升 ≥10pp | 剪掉 HAT |

**伪代码**：

```python
def hat(ep, t0, delta, K_left, K_right, H_left=None, H_right=None):
    obs = ep.obs.copy()
    if H_left is None:
        H_left  = homography_from_delta(K_left,  delta, plane_n, plane_d)
        H_right = homography_from_delta(K_right, delta, plane_n, plane_d)
    obs.head_left[t0:]  = warp(obs.head_left[t0:],  H_left)
    obs.head_right[t0:] = warp(obs.head_right[t0:], H_right)
    act = ep.actions_ee.copy()
    act[t0:, :3] += delta
    if t0 > 0:
        act = insert_bridge(act, t0, frames=8)
    if not valid_ik(act) or collides(act):
        return None
    return obs, act
```

**限制**：

- 平面假设对高架子/立体物不完全成立；H 只对桌面附近的点精确，架子上方会有视差误差。
- 腕部相机在抓取前会看到不同的相对位置；若模型强依赖腕部，HAT 的腕部不变假设会失效。消融腕部输入；必要时对腕部做小平移或丢弃。
- 人手遮挡/接触无法用 HAT 合成；合成手 mask 只能做感知鲁棒性，不能替代真机人扰。
- 官方 K 是数据集标定，部署相机可能不同；HAT 只用于训练增广，不要求部署 K 完全一致。

### 3.5 REV-AUG（可逆步骤时间反演）

**可逆步骤**（从 rubric 语义识别）：

- 拉链：ZipUp、PackBag（拉上书包拉链）、OrganizePencilCase、StorePaddle；
- 拧盖：PourOutMedicine（打开/拧回）、SyringeWaterTransfer（吸/注？不是严格可逆，慎用）；
- 折叠：FoldTowel（对折/翻开）；
- 开合：OrganizeStationery（合上/打开文具盒）、PackPhone（盖上/移开外壳）、StoreEarphones（盖盖/开盖）；
- 堆叠：StackBowls（叠上/拿下第二个）、PaperCupStacking（叠/取）；
- 插拔：PlugCharger/PlugInEthernet（插入/拔出，慎用，接触力不同）。

**方法**：

1. 从 RUBRIC-MAP 的步骤段提取子轨迹（start/end）。
2. 对可逆步骤，时间反演动作序列：`a'_t = a_{T-t}`（EE 位置/姿态反转；夹爪保持闭合/接触；速度取反）。
3. 检查碰撞/关节限位/视觉合理性；只保留物理可行的反演。
4. 生成配对：`(forward, reverse)`；训练**方向分类器**（progress vs regress）和**恢复策略**（检测到 regress 后重做 forward）。
5. 恢复策略可用同一动作专家 + 方向条件（`direction=+1`），不需要新模型；方向分类器是轻量头。

**伪代码**：

```python
def rev_aug(ep, step):
    if not step.reversible:
        return None
    seg = ep.actions[step.start:step.end]
    rev = seg[::-1].copy()                     # 时间反演，不是镜像反射
    rev[:, 6:] = seg[0, 6:]                    # 夹爪保持接触/闭合
    if not valid_ik(rev) or collides(rev):
        return None
    return ep.obs[step.start:step.end], rev
```

**验证**：

- 视觉抽检 50 段：反演是否像“人把状态弄回去”；不像则只保留拉链/盖子/折叠三类。
- 真机 2 任务×10 次：在人扰/回退后，恢复策略 vs 重试 baseline，提升 ≥10pp 才保留。
- 与 HAT 组合：HAT 负责“移动”，REV 负责“回退”；两者互补，不叠加到同一帧避免过度失真。

### 3.6 外观/背景/干扰物 + 等变/不变损失

**增广**：

- 背景：分割桌面/背景；用不同 session 的桌面纹理/颜色替换；保持光照方向/阴影近似；避免把目标物体替换掉。
- 干扰物：官方备注的干扰物（笔、胶带、夹子、零食等）；在桌面空闲区粘贴 mask；不遮挡目标/目标容器；每任务 1–3 个。
- 物体外观：同任务其他实例的颜色/纹理/尺寸；用图像替换 + 分割；未见物品轴优先用**不同实例**而不是同实例变色。
- 语言：5 条复述随机采样；不把语言当主轴；可做同义改写，但不作为评测轴。

**损失**：

```
L = L_flow + λ_s L_step + λ_b L_boundary + λ_c L_contact + λ_g L_grasp
    + λ_eq L_eq + λ_inv L_inv
L_eq  = ||π(o_shift) − T_δ π(o)||²          # HAT 对；EE 空间平移；只用头部相机
L_inv = ||π(o_aug) − π(o)||²                # 外观/背景/干扰物对
```

- `λ_eq`/`λ_inv` 从 0 ramp 到 0.05–0.1；干净数据 ≥50%；对 target 不做 stop-gradient（配对目标就是变换后的动作），但要监控坍缩（若 π 输出常数，L_eq/L_inv 很小但任务损失会爆）。
- `L_eq` 只在头部相机对；腕部不满足严格等变，不纳入。
- `L_inv` 对外观/背景/干扰物；不用于人扰/位置（那些用 `L_eq`）。
- 等变损失是**训练时自监督**，不需要新标签；推理零开销。

### 3.7 RUBRIC-EXEC

**进度头**：`p_k(t) = P(step k complete | o_t)`；用 RUBRIC-MAP 标签训练；推理时单调校准（每步概率不减，除非检测到回退）。

**边界 best-of-K**：

```python
def act(obs, state):
    p = progress_head(obs)                  # (K,)
    if not at_boundary(p, state):
        return action_expert(obs, state)     # K=1
    cands = [action_expert(obs, state, seed=i) for i in range(2)]
    scores = []
    for a in cands:
        p_next = rollout_progress(p, a)      # 轻量预测，不执行
        scores.append(sum(s[k]*p_next[k] for k in range(K)))
    return cands[argmax(scores)]
```

- K=2；只在步骤边界（`p_k` 跨阈值/边界头触发）；避免每帧翻倍。
- `rollout_progress` 不是完整世界模型：用进度头的**一步预测**（当前 p + 动作 chunk 的特征），或直接用 `p` 的置信度 + 动作平滑度打分；不执行、不搜索。
- 平票选更短/更平滑/更接近当前状态的 chunk。

**时间感知保分**：

- 估计剩余时间 `T_rem = 180 − t`；估计下一步时间 `T_next`（任务/步骤中位数，从数据统计）。
- 若 `T_rem < T_next + margin`，进入 **secure**：保持当前步骤的稳定状态（不开始新步骤）；若当前步骤已完成，保持/退回安全位；不硬冲导致回退。
- margin 5–10s；按任务调试校准；不要在最后 10s 开始长步骤（如 FoldTowel 的 5 步、Toolbox 的锁）。

**回归检测/恢复**：

- 若 `p_k` 下降 >τ（如 0.2）或方向分类器判 regress，触发：
  - 轻：re-approach 当前目标（HAT 平移后的位置）；
  - 重：重做当前步骤（REV-AUG 训练的 direction=+1 条件）；
  - 放弃：若剩余时间不足，secure 当前状态，保步骤分。
- 人扰轴（移动/拿走/回退）主要靠这条；没有这条，模型会“对着旧位置继续执行”。

**延迟**：

- 进度头（共享特征上）<2ms；方向分类器 <1ms；best-of-K 只在边界，动作专家 K=2 的额外成本约 2×；若 p99 超 150ms，降 K=1 或减 chunk。
- 4 相机 240×320；chunk 8–16；N ports 用 batch/queue；状态隔离。

### 3.8 与 FACT-VLA 整合 + 训练课程

**层**：

1. 感知：4 相机 + proprio + language → 冻结/半冻结编码器。
2. FACTOR：接触代理（夹爪滞止、EE 速度、视觉接近）→ 接触相位。
3. RUBRIC-MAP：步骤进度/边界（新）。
4. 动作专家：flow matching/diffusion；EE 动作；chunk。
5. CAC：柔顺/尾段安全（第 10 轮）。
6. RUBRIC-EXEC：边界/best-of-K/保分/恢复（新）。

**课程**：

- **Stage A（base）**：33k 官方数据，EE 动作，标准 BC/flow；4 相机；chunk 16；无增广。目标：clean/position 轴可用。
- **Stage B（rubric）**：加 RUBRIC-MAP 标签；步骤平衡采样；进度/边界辅助损失；DAG 约束。目标：步骤分 + 首步。
- **Stage C（axis）**：HAT + REV-AUG + 外观/背景/干扰物；等变/不变损失；干净数据 ≥50%。目标：severe 轴。
- **Stage D（exec）**：RUBRIC-EXEC 校准；best-of-K K=1→2；时间感知；debug 通道。目标：保分/恢复。
- **Stage E（submit）**：全量 32×10；只在前一阶段门控通过后。

**损失权重起点**：`λ_s=0.1, λ_b=0.05, λ_c=0.05, λ_g=0.05, λ_eq=0.05, λ_inv=0.05`；按验证集调，不按榜单调。

**资源阶梯**：

| 档 | 资源 | 模型 | 数据 | 能做什么 |
|---|---|---|---|---|
| R0 | 1×24GB | 2B/3B VLA + LoRA | 10–30% | rubric 标签 + 小规模 HAT 验证；不做 6B |
| R1 | 4×A100 80GB | 3B/6B + LoRA | 50–100% | 主实验；3 seeds 中的 1–2 |
| R2 | 8×A100/H100 | 6B + LoRA/全参 | 100% | 完整课程 + 消融 + 全量提交 |

若只有 R0，优先做 RUBRIC-MAP + 首步诊断 + 小规模 HAT；不要硬上 6B。方法 backbone-agnostic。

### 3.9 单模型合规 / 部署

- 一个 checkpoint 包含编码器、动作专家、进度头、边界头、方向头、接触头；best-of-K 采样同一模型；无第二模型、无外部 API。
- HAT/REV/外观增广**离线**；推理不调用增广器。
- N ports：每个端口独立 `state`（历史、进度、rubric、计时）；模型共享；推理服务线程安全；端口间不共享 episode 状态。
- token：`metadata["token"]` 和每次 `meta.token` 一致；从 `UNIBOT_SUBMISSION_TOKEN` 读取。
- `obs_delta_indices` 最小化；`image_resize` 240×320；`action_chunk_size` 8–16；`control_space="ee"`（回退 `joint`）。
- 延迟目标：p50 <80ms，p99 <150ms；4 相机 + chunk 16；best-of-K 只在边界。
- 失败安全：动作限幅/工作空间/关节限位/急停；异常时返回保持/回撤 chunk；不返回 NaN/超范围。

- EXEC：K=1/2/3；边界触发 vs 每帧；时间感知 on/off；回归检测 τ。
- 控制空间：ee vs joint；chunk 8/16/32；图像 240×320 vs 320×480。
- 数据：random split vs session-grouped vs robot-held-out；全量 vs 2 步任务过采样。

### 4.4 预算 / 时间线 / 资源阶梯

**10 周**（按 R1 4×A100 估计；R2 可压缩，R0 需拉长）：

| 周 | 工作 | 产出/门 |
|---|---|---|
| 1 | 规则/接口复现；rubric 解析；160 段标注启动 | G0；schema |
| 2 | 标注完成；RUBRIC-MAP 训练；AXIS-BENCH 切分 | G1；bench v0 |
| 3 | HAT 几何/单应/动作重定向；REV 可逆段 | G2 初版 |
| 4 | HAT/REV 离线验证；外观增广；等变/不变损失 | G2/G3 初版 |
| 5 | Stage A/B 训练；首步诊断；步骤分基线 | B0–B3 |
| 6 | Stage C 训练；severe 轴评估；消融第一轮 | B4–B6；G3 |
| 7 | Stage D 校准；debug 2 任务×10 | G4 |
| 8 | debug 扩展 4–8 任务；修首步/末步；第二 seeds | G4/G6 |
| 9 | 全量 32×10 第一次；错误分析；冻结 | G5 |
| 10 | 全量第二次（如允许）；报告/复现 | 最终 |

**调试/全量 slot**：

- 单任务调试：先 2 个 2 步（HangCup、ZipUp）+ 2 个 3 步（PlugCharger、ArrangePlates）+ 1 个 5 步（FoldTowel）；每任务 10 次；重点测首步/末步/人扰。
- 全量：32×10=320 次；只在 G5 后；预留 1 次重跑。
- 若规则允许多次提交，先交安全模型（B3/B4）再交 B7；若只保留最新，等 G5 后一次交。

**计算粗估**：33k eps × ~200 帧 ≈ 6.6M 帧；4 相机；6B + LoRA；batch 64；2–3 epochs；4×A100 约 2–3 周/轮；R2 8×A100 约 1–1.5 周/轮。HAT/REV 离线 CPU/GPU 预处理 2–3 天。标注 160 段约 3–5 人日。

### 4.5 统计协议

- 分组：session-grouped + robot-held-out；同一 session/robot 不跨 split。
- 3 seeds（至少 2）；报告 mean±95%CI；paired bootstrap；不报单任务/单轴 n=2。
- 预注册门控（G0–G7）；不因榜单结果改门控；消融与主实验同 split。
- 真机 debug 每任务 10 次；报告 Wilson CI；不把 1–2 次差异当结论。
- 榜单比较标注日期/来源；首页表 vs 独立页不一致时以首页表为准并注明。

## 7. 开放问题

1. **步骤分公式**：是完成步骤分值累加，还是最后完成步的分值/归一化？超时/部分完成如何给分？——调试通道反拟合。
2. **扰动幅度/时机**：官方备注只给方向，不给 δ/时刻；——debug 扫描 2/5/10cm 与早/中/晚期。
3. **部署相机参数**：接口不暴露 K/基线；数据集 `camera_params` 是否与测试机器人一致？——debug 用已知物体尺寸反推/只用训练增广。
4. **多次提交规则**：是否保留最好成绩/最新成绩？——赛前确认；先交安全模型还是等最终。
5. **外部数据政策**：43+ 非挑战赛 G1 Dex1 数据集是否允许？——默认 OFF，书面确认后再开。
6. **人扰协议**：人手何时/如何介入？是否允许接触机器人？——安全策略/急停；合成数据只做训练。
7. **排行榜更新频率**：首页表与独立页何时同步？——所有引用标注日期。
8. **步骤分是否按任务归一化**：32 个任务等权还是按步数加权？——规则未写明；用调试数据反推。
