# 第 55 轮（承接第 54 轮 v31 GroundEdge-GenSim+++；灵感循环第 6 轮；本轮灵感：「续航能力」×「用户需求分析」）

> 第 54 轮把技能组合升级为"动作-鲁棒性双证书"，但仍暗含两个未言明的假设：(i) 鲁棒性越高越好，能量/资源视为近似无限；(ii) 任务动作序列 A_T 是外部给定的常量。本轮用「续航能力」打破"资源无限"，用「用户需求分析」打破"任务给定"。核心矛盾：H22：鲁棒性与续航天然互斥——冗余、慢速、多传感、反复校验都在吃电，固定 ρ_min 会制造"鲁棒性过剩"并榨干续航；H23：任务规格本质是用户需求的投影，需求不同则 ρ_target、E_target 不同，需求漂移会让已签发证书静默过期。

## 0. 直觉与动机

**灵感 1（续航是第一类资源，而非事后指标）**
直觉：技能 S 不只在动作空间上占用 α_S、在扰动空间上拥有 ρ_S，还在时间轴和上下文 c 上以能耗率 ε_S(a,c) 消耗能量。给定电量 SoC，技能能跑多久是 `E_S=(SoC−SoC_min)/ε_S`，且它随地形、负载、温度强烈非线性变化。因此续航不是"最后再算一下"，而应与动作可行性、鲁棒性并列，成为组合的一等约束。

**灵感 2（把鲁棒性与续航统一为"失效预算"）**
直觉：ρ_S(d) 回答"在维度 d 上还能承受多少扰动才失效"，ε_S(d) 回答"在维度 d 上还能消耗多少能量/循环才耗尽"——两者其实是同一对象的两面：**到失效为止还剩多少预算**。定义失效预算谱 `β_S(d)=(ρ_S(d),ε_S(d))`，组合时两种预算以不同规律传递（扰动预算近似取 min，能量预算非线性叠加并计转换/热损），使第 53–54 轮的所有证书获得统一的"预算语义"。

**灵感 3（用户需求分析 → 任务规格是需求的投影）**
直觉：世界上不存在"通用任务 A_T"，只有需求向量 u。用 Kano/QFD 把 u 映射为规格 `T(u)=(A_T,ρ_target(u),E_target(u),θ_u,w)`：must-be 需求是硬约束（必达），performance 需求线性加权，attractive 需求机会性投入。于是 ρ_min、E_min 从全局常数退化为需求的函数，动作覆盖与需求覆盖成为一对对偶概念。

**灵感 4（按需鲁棒 ROD → 用需求在前沿上选工作点）**
直觉：鲁棒性与续航构成一条 Pareto 前沿 `PF={(ρ,E)}`。多一分鲁棒就少一分续航。固定 ρ_min 会在低需求场景过度鲁棒、白耗电；ROD 在满足 must-be 硬约束的前提下，按用户效用在前沿上选点 `β*(u)`，把"军备竞赛式鲁棒"改成"够用就好"。

**灵感 5（续航预算的按需分配 + 五元证书）**
直觉：总能量 B 按阶段与需求重要性分配 `{b_k}`：must-be 阶段预留保底、performance 阶段按权重比例、attractive 阶段 best-effort 可抢占，形成续航契约 C_E；边端 SoC 残差超预期即经 Explain 回路触发云端重规划。联合证书从四元扩为五元 `J±=(ρ,A_cert,ε_cert,U_cert,γ_ce,δ_a,δ_e)`，金字塔新增能量层 𝔼 与需求层 𝕌。

## 1. 形式化定义（增量：定义 121–128）

**定义 121（能耗剖面与续航半径）** 上下文空间 C（地形/负载/温度）。技能 S 的能耗率 `ε_S : A×C → R_{≥0}`，续航半径 `E_S(a,c) = (SoC(a,c) − SoC_min)/ε_S(a,c)`，续航谱 `ε_S(d)` 为各维度下能耗率的上包络。**关键：ε 不可加**，`ε_{S1⊗S2}(a,c) = ε_{S1}+ε_{S2}+Δε_trans+Δε_thermal`。

**定义 122（失效预算谱）** `β_S(d) = (ρ_S(d), ε_S(d))`，偏序 `β≽β'` 当且仅当两分量均不劣。组合预算 `β_{S1⊗S2}(d) = (compose_ρ(ρ_1,ρ_2), compose_ε(ε_1,ε_2))`。

**定义 123（续航感知组合可行性）** 路径 π 在需求 u 下能量可行当且仅当 `E(π) = (SoC_0 − SoC_min − B_reserve)/mean_{a∈π} ε(a,c) ≥ E_target(u)` 且 `ρ(π)≽ρ_target(u)`。

**定义 124（需求空间、Kano 与规格投影）** 需求 `u∈[0,1]^m`，权重 w，Kano 分类 `κ:[m]→{M,P,A}`。规格投影 `T(u)=(A_T(u),ρ_target(u),E_target(u),θ_u,w)`，其中 `ρ_target(u)` 取 must-be 维度的需求下界。**must-be 违反即整体失败**。

**定义 125（需求覆盖）** `cover_U(π,u) = Σ_i w_i·sat_i(π,u)/Σ_i w_i`，`sat_i∈{0,1}`（按验收阈值）。部署需 `cover_U≥θ_u` 且 `∀κ(i)=M: sat_i=1`。

**定义 126（相容域与 Pareto 工作点）** `F(u)={π : cover_A(π,T(u)) ∧ β(π)≽β_target(u) ∧ cover_U(π,u)≥θ_u}`；前沿 `PF={β(π): nondominated}`；按需工作点 `β*(u)=argmax_{β∈PF∩F(u)} [utility(β,u) − λ·ε(β)]`。

**定义 127（续航预算契约）** `C_E=(B,{b_k}_{k=1..K},{r_k})`，`Σ_k b_k ≤ B − B_reserve`；`r_k` 为 must-be 阶段保底比例。边端观测 SoC_e，若 `SoC_e < ŜoC_e − δ_e` 触发重规划。

**定义 128（五元联合证书与时效）** `J±=(ρ,A_cert,ε_cert,U_cert,γ_ce,δ_a,δ_e,evidence)`，`ε_cert=(E_pred,E_buffer,δ_e)`，`U_cert=(u,κ,cover_U,T(u))`。可部署当且仅当动作核心对齐、`ρ≽ρ_target(u)`、`E_pred≥E_target(u)`、`cover_U≥θ_u`、`δ_a<Θ_a`、`δ_e<Θ_e`。当需求漂移 `‖Δu‖>Θ_u` 或能量模型漂移 `>Θ_e` 时证书过期，须重签。

## 2. 关键算法 伪代码

### IP-121 EPC（Energy Profile Characterization）

```python
def energy_profile(skill, A, contexts, sensor):
    eps = {}
    for a in A:
        for c in contexts:
            meas = sensor.measure_energy(skill.run(a, c))   # Wh/cycle
            eps[(a, c)] = fit_energy_model(meas, a, c)      # 非线性回归
    return eps

def endurance_radius(eps, A, c, soc, soc_min):
    worst = max(eps[(a, c)] for a in A)                     # 最坏动作下界
    return (soc - soc_min) / worst
```

### IP-123 EAC（Endurance-Aware Composition）

```python
def endurance_aware_compose(G, K, so_cap, reserve):
    for (i, j) in G.edges:
        e = G[i][j].energy + transition_energy(i, j) + thermal_overhead(i, j)
        rho = compose_robustness(G.nodes[i].rho, G.nodes[j].rho, K)
        G[i][j].beta = (rho, e)
    PF = pareto_front([path_beta(p) for p in all_paths(G)])
    return prune_dominated(G, PF)
```

### IP-124 UNA（User Need Analysis）

```python
def user_need_analysis(interviews, usage_logs):
    u, w = elicit_needs(interviews, usage_logs)   # 多源三角验证
    kappa = kano_classify(u)                      # M / P / A
    T = qfd_map(u, w, kappa)                      # 需求→动作序列与目标
    return NeedSpec(u, w, kappa, T)

def derive_targets(need):
    rho_target = {d: need.level[d] for d in need.must_be_dims}
    E_target = need.service_hours * need.repeat_rate
    return rho_target, E_target, need.theta_u
```

### IP-125 ROD（Robustness-on-Demand）

```python
def robustness_on_demand(PF, need, lam):
    feasible = [b for b in PF if satisfies_must_be(b, need)]
    return max(feasible, key=lambda b:
               utility(b, need) - lam * b.energy)
```

### IP-126 EBA（Endurance Budget Allocator）

```python
def allocate_endurance(B, phases, need):
    must = [k for k in phases if need.kappa[k] == 'M']
    perf = [k for k in phases if need.kappa[k] == 'P']
    reserve = B * sum(need.reserve_ratio[k] for k in must)
    rest = B - reserve
    b = {k: B * need.reserve_ratio[k] for k in must}
    for k in perf:
        b[k] = rest * need.w[k] / sum(need.w[j] for j in perf)
    assert sum(b.values()) <= B            # 预算守恒
    return b
```

### IP-127 UNC（Unified Need-Endurance Certificate）

```python
def unified_certificate(pi, u, gamma_ce, budgets):
    A_core = intersect_action(pi)
    E_pred = predict_endurance(pi, budgets.context)
    rho = compose_robustness_chain(pi)
    cover = need_coverage(pi, u)
    if not cover_action(pi, u.T.A_T):        return ('reject', 'action')
    if not dominates(rho, target_rho(u)):     return ('reject', 'robustness')
    if E_pred < target_E(u):                  return ('reject', 'endurance')
    if cover < u.theta or not must_be_ok(pi, u):
                                              return ('reject', 'need')
    return ('ok', J_pm(rho, A_cert(A_core), E_cert(E_pred, buffer),
                       U_cert(u, cover), gamma_ce, delta_e=E_drift(E_pred)))
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| EPC | O(|A|·|C|·T_meas) | O(|A|·|C|) | 能耗模型校准、外推有界 |
| EBS | O(|S|²·|𝔇|) | O(|S|·|𝔇|) | 预算半序 sound、组合单调 |
| EAC | O(|S|²·|A| + |PF|) | O(|S|² + |PF|) | 能量非可加项闭合 |
| UNA | O(m·N) | O(m) | Kano must-be 分类可靠 |
| ROD | O(|PF|) | O(|PF|) | must-be 硬约束不被效用淹没 |
| EBA | O(K) | O(K) | 预算守恒 `Σb_k≤B` |
| UNC | O(|π|·|A| + |𝔇|) | O(|A| + |𝔇|) | 五元证书 sound |
| NDR | O(m·T) | O(m) | 漂移 tripwire 不误触发 |

**正确性定理（Need-Endurance-Aware Deployment Soundness）**
假设第 54 轮 (A22)–(A28) 成立，并新增：**(A29)** `ε_S` 由结构化能耗实验校准，误差 ≤ δ_ε；**(A30)** SoC 模型在上下文域上有界误差 ≤ δ_soc；**(A31)** 需求规格稳定（`‖Δu‖≤Θ_u`）且 must-be 分类正确率 ≥ 1−ε_κ；**(A32)** 能量非可加项上界已知且有 `B_reserve` 兜底。
则对 `π*∈F(u)`：
```
P(success ∧ cover_U ≥ θ_u) ≥ 1 − Σ_d(1−ρ_target(d)) − P(E_pred<E) − ε_κ − β_E − P(δ_a>Θ_a)
```
关键：**需求先定预算目标**、**能量预算有兜底**、**前沿选点不越过 must-be**。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 能耗模型非线性/电池老化 | 高 | 在线校准 + 老化项 + 保守 buffer |

## 6. 本轮最大风险

**一句话**：五元证书的 soundness 四重依赖能耗模型在极限负载下的校准、SoC 模型的有界误差、Kano must-be 分类的正确、以及能量非可加项的上界；一旦能耗被系统性低估或 must-be 被错判，系统会在任务中途"续航假象"式断电、或把续航预算错配给伪需求，故必须以 **保守能量 buffer + 三角验证的需求获取 + 漂移 tripwire** 三重护栏，宁可少承诺服务时长，绝不把"电量还能撑住"的乐观外推当成部署前提。

# 第 55 轮产物 · 创新点清单 v32：GroundEdge-GenSim++++（EPC×EBS×EAC×UNA×ROD×EBA×UNC×NDR）

> 承接第 54 轮产物 v31。本轮在"动作-鲁棒性双证书"之上加入 **需求-续航维度**，把鲁棒性与续航统一为"失效预算"，并用 Kano/QFD 把任务规格还原为用户需求的投影：

```python
def need_drift_respec(J_old, u_new, E_new, theta_u, theta_e):
    drift_u = norm(u_new - J_old.U_cert.u)
    drift_e = abs(E_new - J_old.eps_cert.E_pred) / J_old.eps_cert.E_pred
    if drift_u <= theta_u and drift_e <= theta_e:
        return ('valid', J_old)                  # 证书仍有效
    return ('expired', respec(J_old, u_new, E_new))
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |

**正确性定理（Need-Endurance-Aware Deployment Soundness）**
假设第 54 轮 (A22)-(A28) 成立，新增 **(A29)** `ε_S` 由结构化能耗实验校准，误差 ≤ δ_ε；**(A30)** SoC 模型在上下文域上有界误差 ≤ δ_soc；**(A31)** 需求规格稳定（`‖Δu‖≤Θ_u`）且 must-be 分类正确率 ≥ 1−ε_κ；**(A32)** 能量非可加项上界已知且有 `B_reserve` 兜底。则对 `π*∈F(u)`：
```
P(success ∧ cover_U ≥ θ_u) ≥ 1 − Σ_d(1−ρ_target(d)) − P(E_pred<E) − ε_κ − β_E − P(δ_a>Θ_a)
```
关键：**需求先定预算目标**、**能量预算有兜底**、**前沿选点不越过 must-be**、**漂移触发重签**。

## 5. 本轮最大风险

**一句话**：五元证书的 soundness 四重依赖能耗模型在极限负载下的校准、SoC 模型的有界误差、Kano must-be 分类的正确、以及能量非可加项的上界；一旦能耗被系统性低估或 must-be 被错判，系统会在任务中途"续航假象"式断电、或把续航预算错配给伪需求，故必须以 **保守能量 buffer + 三角验证的需求获取 + 漂移 tripwire** 三重护栏，宁可少承诺服务时长，绝不把"电量还能撑住"的乐观外推当成部署前提。
