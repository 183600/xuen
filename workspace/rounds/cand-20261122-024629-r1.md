# 第 2 轮（UniBot 线 · 第 2 轮；本轮灵感：「双臂协作」×「成本控制」）

> **延续声明**：不重新基线化。第 1 轮 UniBot-SAGE 的 U1–U12 / L1–L7 / E601–E618 全部保留为 v1；本轮在其上做「一个协作层 + 一个预算层 + 一个闸门」，新增 U13–U24 / L8–L14 / E619–E634。v1 的剪枝预案（保 IP-06/02/03，IP-01 先过合规）继续有效。
> **数据纪律**：本轮不新增赛事事实断言。所有榜单数字沿用 v1 已核实的 teaser 缓存（8 个模型 × 32 个任务，检索日期 2026-11-17）；新增分析只做**可复现的二次统计**，并明确标注「人工先验 / 待 E619 核验」。

## 0. 上一轮留下的三个未决口

1. **双手被当成一只手。** v1 把抓握做成单臂隐变量 `g_t`，但没有建模「两只手如何分工」。32 个任务含双手协调；在 Unlock / Open Pill Bottle / Plug In Ethernet / Fold Towel / Zip Up 这类任务里，「一只手稳住、一只手操作」往往就是成败分界。v1 的 IP-02 只能「重抓」，不能「换手」，也不能让第二只手提供外部约束。
2. **所有改进都默认预算是无限的。** v1 的 IP-01/02/03/04 都在增加模块（专家、抓握判定器、上下文编码器、在线适配器），但没有一个统一的**资源分配器**回答：这一步的延迟 / 算力 / 风险预算该给谁？在 105 ms 的 per-step 预算和 N 端口并发下，「每个模块都开」本身就是一种未计价的成本。v1 的 P1 说「只优化终态成功」，但没有说「为了终态成功，愿意花多少成本」。
3. **成本与协作没有连起来。** v1 的 IP-02 把「重抓」当成默认恢复手段，但重抓要先把物体放回 / 重新接近，成本高且会破坏已完成的阶段；第二只手如果能把物体稳住或直接接过去，恢复成本会显著下降。**双臂不是额外自由度，而是一种降低恢复成本的技术。**

## 1. 直觉解释（先直觉，后定义）

### 1.1 「双臂协作」给的不是两只手，是**约束 + 角色 + 换手**

- **直觉**：很多桌面任务不是「两只手各做各的」，而是「一只手提供约束，另一只手才能完成动作」。拧瓶盖：一只手必须稳住瓶身，另一只手才能施加扭矩；插网线：一只手稳住接口 / 线缆，另一只手才能对准插入；折毛巾 / 拉拉链：两只手必须同时维持织物的张紧。单臂不是「少一只手」，而是**少了一个外部约束**。
- **形式化要点**：把任务看成需要 `m` 个接触约束；单夹爪最多提供 1 个抓握约束，环境最多提供 `e` 个外部约束；若 `m > 1+e`，单臂原理上不可行（L8）。第二臂的边际价值 = `P(m > 1+e) − P(物体已被环境稳定)`。
- **角色**：`ρ_t = (ρ_L, ρ_R) ∈ {act, hold, idle}²`；同一时刻至多一个主动操作臂，除非任务要求双手同步。角色不是「多一个策略」，而是同一 checkpoint 内的条件化（P9）。
- **换手**：handover 是「不把物体放回桌面」的重新抓握；它把 v1 IP-02 的「重抓」从「退回到桌面」变成「在空中交接」，理论上降低恢复成本（L10），但引入协调延迟与滑移风险。

### 1.2 「成本控制」给的不是省钱，是**影子价格 + 预算分配**

- **直觉**：机器人策略不是免费 oracle。每一步推理都在消耗 per-step 延迟、算力、显存、动作风险、干预风险。官方明确采集 per-step 延迟及其波动、动作统计规律性并可能据此评估可信度 ⇒ 成本首先是**可信度约束**，其次才是内部资源分配。
- **关键观察（来自 teaser 缓存的二次统计）**：8 个模型的平均 episode 时长几乎相同（43.7–45.2 s），任务内 `corr(dur, succ)` 均值仅 −0.011 ⇒ **「做得快」不是计分货币**；真正稀缺的是 per-step 延迟与动作风险，而不是 episode 墙钟时间。这个观察决定了成本控制的方向：不要为了缩短 episode 牺牲成功率；要把省下来的推理预算搬到「最后一环」（对齐 / 插入 / 释放）和「抓握不确定」的相位。
- **形式化要点**：成本向量 `C(o) = (latency, compute, motion, risk, intervention)`；预算 `B` 含不可挪用的安全储备 `B_safe`；影子价格 `λ` 把成本换算成「成功点数」，决策规则是 `VOC(o) = Δsuccess(o) − λ·ΔC(o) > 0`（L11）。`λ` 不是超参，而是由预算约束对偶上升得到：预算松时 `λ→0`，倾向多用协作 / 多算；预算紧时 `λ` 增大，退回低成本路径，但安全盾不受 `λ` 影响。

### 1.3 合成：双臂是**降低恢复成本**的技术，成本控制是**决定何时用双臂**的闸门

- **直觉**：第二只手最值钱的时候，不是「平时帮一点忙」，而是「第一只手失败时，不用把物体放回桌面就能救回来」。因此双臂的收益主要落在**恢复成本**上：support arm 稳住物体 → 主动臂可以在原地重抓 / 换抓；handover → 不中断任务地交换角色。成本控制则决定：这个 support / handover 的边际成功增益，是否值得它的延迟 / 风险 / 干扰成本。
- **一个可检验的推论**：**双臂会降低干预的影子价格**。v1 的介入准则是「仅在高置信未抓住时重抓」；若 support arm 把恢复成本从 `c_R` 降到 `c_H < c_R`，则最优介入阈值 `p* = λc/Δ` 下降，允许更多「低成本、高精度」的介入，从而提高终态成功率。这把两个灵感词变成了一个闭环，而不是两个并列模块。
- **路线**：**Cost-Budgeted Coordination（CBC）**：Belief（共享物体信念）→ Roles（角色分配）→ Options（idle / support / act / handover / two-hand）→ Price（VOC 门控）→ Execute（缝合 / 安全滤波）→ Audit（成本账本）。仍然是一个 checkpoint、一个 API。

## 2. 量化动机（可证伪，不靠新事实）

### 2.1 高双臂需求任务是否更难？——一个预注册的人工先验

按「是否需要持续稳住物体 / 容器 / 接口，或双手同步维持形变」这一条**事先写死**的规则，把 32 个任务分成高 / 中 / 低三组（完整名单见产物区 §2.1），在 teaser 缓存上做二次统计：

| 组别（人工先验，待 E619 核验） | 任务数 | 平均成功率 | 跨模型 sd | per-task oracle |
|---|---:|---:|---:|---:|
| 高双臂需求 | 12 | **23.49** | 6.42 | 33.09 |
| 中（支撑有益） | 10 | 26.12 | 4.71 | 33.95 |
| 低（单臂足够） | 10 | **26.24** | 5.49 | 35.01 |

- 高组比低组平均低 **2.75 分**；即便取每个任务的最好模型，高组 oracle 仍低 **1.92 分** ⇒ 这不是「某个模型不擅长」，而是**任务本身更难**。
- 8 个模型中 **7 个**在高组更差；Cliff's δ = **−0.52**（大效应）。唯一例外是 WALL-OSS-0.5（高组反而高 1.65 分），说明「双臂需求」不是单一能力轴，而是有模型间异质性的。
- 高组内部跨模型 sd 也更大（6.42 vs 5.49）⇒ 角色 / 协作策略的差异可能在这里被放大，路由与协作有信号。
- **保留意见**：这是人工分组，不是官方标签；E619 必须用官方数据中的左右臂运动学自动挖掘角色片段，检验「高组」是否真的对应更多的 hold / handover 片段。若 E619 否定，则 IP-10 降级。

### 2.2 成本到底是什么？——时长不是计分货币

| 观测 | 数值 | 对成本控制的含义 |
|---|---|---|
| 8 个模型的平均 episode 时长 | 43.74–45.19 s（极差 1.45 s） | 模型间时长几乎无差异；「跑得快」不区分模型 |
| 任务内 `corr(dur, succ)` | 均值 −0.011，中位 0.006 | 在任务内，做得快与成功几乎无关 |
| 任务平均时长范围 | 29.33–59.70 s | 任务间时长差异大，但那是任务属性，不是策略可优化项 |
| 高双臂组 vs 低组平均时长 | 45.10 vs 44.15 s | 高组略慢，但差异远小于成功率差异；「慢」不是主因 |

**结论**：在 UniBot 的计分与评测口径下，成本控制不应该去优化 episode 时长；它应该优化 **per-step 推理延迟**（硬预算）、**动作 / 干扰风险**（可信度与失败成本）、**干预次数**（恢复成本）和**标注 / 训练成本**（研究成本）。这也解释了为什么「多花一点动作时间让第二只手稳住」在分数上几乎是免费的——真正要计价的是协调推理与干扰风险。

### 2.3 为什么是现在：v1 的三个模块正好提供了计价所需的信号

- IP-02 的抓握隐变量 `g_t` 提供「什么时候可能失败」的信号；
- IP-06 的六因子分解提供「失败发生在哪一相位」的信号；
- IP-03 的延迟 / 缝合 / 审计提供「这一步花了多少成本」的信号。
⇒ 不需要新数据就能先做一个**成本账本 + 规则版预算分配器**；学习版价值头可以后置。

## 3. 研究问题（Q6–Q10）

- **Q6（角色可观测性）**：在只有左右腕相机、左右抓手标量、左右 EE 位姿 / 速度的观测下，能否把「谁在 act、谁在 hold、谁 idle」估成带置信度的角色后验？角色条件化是否比统一单策略在**高双臂需求子集**上更好？收益来自表达力还是数据效率 / 信用分配？
- **Q7（支撑臂的边际价值）**：把第二臂当作「动态夹具」（移动到接触位姿并保持）而非主动操作臂，能在插入 / 旋转 / 形变任务上带来多少成功率增益？这个增益能否在**离线**用角色 dropout / 反事实增强估计出来，从而不必每次真机试错？
- **Q8（换手经济学）**：handover 相对「放回桌面再重抓」的期望恢复成本何时更低？在无触觉、单自由度夹爪下，换手的滑移风险如何定价？换手应该只在哪些相位、以什么最大次数启用？
- **Q9（预算分配）**：给定 per-step 延迟预算、每 episode 干预上限、风险上限，如何把预算分配到 reach / grasp / transport / align / insert / release 六个相位？「按边际成功增益 / 成本做 water-filling」是否优于固定节拍或固定 chunk？
- **Q10（合规与可审计）**：角色、共享信念、成本头都在一个 checkpoint 内是否仍满足「单模型通才」？成本账本、降级链、N 端口隔离能否写成可导出的自证报告，并对齐官方「延迟与动作规律性」的可信度口径？

## 4. 设计原则（P1–P6 之上加 P7–P11）

- **P7 协作是选项，不是默认**：`idle` 永远是可选项；只有 `VOC > 0` 且预算允许时才启用 support / act / handover。默认单臂，双臂 opt-in。
- **P8 成本是一等公民**：每个模块 / 选项都有成本向量与预算；`B_safe` 不可挪用；成本账本可审计；任何超预算都必须触发**显式降级**，不允许静默挪用。
- **P9 角色在 checkpoint 内**：role token + 共享主干 + 左右动作头；不允许外部编排进程、多模型投票或按任务硬编码角色。对外仍是一个 `metadata / get_action / reset` 服务。
- **P10 先支撑后操作，先原地后换手**：升级顺序为 `idle → support（被动稳住）→ in-place regrasp（原地重抓）→ handover（空中交接）→ two-hand active（双手主动）`；每升一级都要重新过 VOC 闸门，且成本 / 风险更高。
- **P11 负结果保护**：若基座在任务 / 相位的成功率低于 `s0`，或角色置信度低于 `c0`，关闭主动协作；双臂默认不启用，避免「为了协作而协作」。若 E620/E621 无正收益，按预注册剪枝，不硬撑。

## 5. 最小可提交闭环（MVP2）与退化链

**MVP2 = v1 MVP（IP-06 代理评测 + IP-02 抓握确认 + IP-03 缝合）+ IP-09 成本账本 + IP-10 角色 / 支撑臂 + IP-12 能力闸门。**
IP-11（换手）排在 support arm 验证之后；IP-13（角色挖掘）是 IP-10 的数据前置；IP-14（成本审计）并入 IP-09 的交付。

**严格退化链（任一环节不可用 ⇒ 行为回退而非漂移）**：

- **Level-0 预算超限 / p99 超预算** ⇒ 关闭主动 two-hand，只保留 support（开环、低频）；
- **Level-1 角色置信度低 / 支撑臂可能干扰** ⇒ 支撑臂保持当前位姿（safe idle），主动臂继续 v1 单臂策略；
- **Level-2 换手滑移风险高 / 换手失败** ⇒ 退回原地重抓；再失败 ⇒ 退回 v1「放回桌面重抓」；
- **Level-3 能力闸门不通过** ⇒ 关闭全部 CBC 协作，只提交 v1 SAGE + 基线安全网；
- **Level-4 任一新增模块异常** ⇒ 整链回退到 v1 的 Level-0…Level-4。

## 6. 预期贡献（可验收）

1. **把双臂从「多一个自由度」变成「多一个约束 + 一套角色 + 一个换手协议」**：给出 role token、共享物体信念、support / handover 的形式化与降级链。
2. **把成本控制从「省钱」变成「影子价格 + 预算分配」**：给出成本向量、`VOC` 门控、water-filling 分配与可审计账本；明确「episode 时长不是计分货币，per-step 延迟与风险才是」。
3. **量化双臂需求与难度的关系**：在 teaser 缓存上给出高 / 中 / 低三组的成功率、oracle、Cliff's δ，并预注册 E619 的核验方式；这是一个可被证伪的公共诊断口径。
4. **把 v1 的抓握恢复升级为「低成本恢复」**：support arm 降低干预成本 ⇒ 降低介入阈值 ⇒ 让 v1 的高精度低召回策略在更多相位可用（L9）。
5. **一套可审计的协作成本报告**：延迟 p50/p99、干预 / 换手次数、风险事件、预算违规、降级次数，全部可导出；N 端口隔离可压测。

## 7. 本轮最大风险

**一句话**：最大风险是「成本—角色」联合估计的误差在未见物体上被放大——我们用人工先验和弱监督估计支撑臂的边际收益与恢复成本，一旦分布漂移，预算分配器会把资源投到错误相位，而支撑臂又可能主动干扰场景，使双臂方案在泛化场景下比单臂更差。

## 8. 下一轮迭代计划（深化与修剪，不推倒重来）

- **深化**：把角色从「三值硬标签」升级为「带时序的角色后验 + 滑移检测」；把 `VOC` 的价值头从规则版升级为用角色 dropout 训练的反事实价值头；把 handover 协议与 v1 IP-02 的抓握确认做成一个统一状态机。
- **修剪预案**：
  - E619 若显示高双臂组与角色片段无显著对应 ⇒ IP-10 降 P2，只保留 support 的规则版；
  - E620 若 support arm 在高双臂子集上 < +1.5 分 ⇒ 关闭主动 support，只保留 idle；
  - E621 若 handover 不优于原地重抓 ⇒ 关闭 handover，保留 in-place regrasp；
  - E623/E624 若成本感知门控不优于固定节拍 ⇒ 退回固定 chunk + v1 介入准则；
  - E626 若能力闸门误关 > 5% ⇒ 收紧阈值或默认全关。
- **保留项**：IP-06、IP-02、IP-03、IP-12（闸门）在任何情况下不砍。

# 第 2 轮产物 · 创新点清单 v2（UniBot 线）：**UniBot-CBC**

> **CBC = Cost-Budgeted Coordination**（成本预算化双臂协作）。
> 延续 UniBot-SAGE（第 1 轮），不推翻；v1 的 U1–U12 / L1–L7 / E601–E618 全部保留，本轮新增 IP-09–IP-14，编号 U13–U24 / L8–L14 / E619–E634。
> **数据纪律**：本轮不新增赛事事实断言。所有榜单统计均来自 v1 已核实的 teaser 缓存 `exp/r16_leaderboard_data.json`（`generated_from: gen_leaderboard.py`，8 模型 × 32 任务，检索日期 2026-11-17）；新增的「高 / 中 / 低双臂需求」分组是**人工先验**，不是官方标签，必须由 E619 核验。teaser 仍是占位表，所有「+x 分」均为预注册目标值，不是已观测结果。
> **合规红线**：单 checkpoint、单 API；角色 / 信念 / 成本头都是网络内部条件化；不做外部编排、不做多模型投票、不读评测侧私有信息；跨端口状态严格隔离；不做「读题即硬编码角色」的分支。

## 0. 本轮结论摘要

**一句话路线**：在 v1「接地 → 技能 → 适应 → 工程」栈上，把**第二只手**当作一种**降低恢复成本的选项**（support / in-place regrasp / handover / two-hand），把**成本**当作一等约束（per-step 延迟、算力、动作 / 干扰风险、干预次数），用一个**影子价格分配器**决定「什么时候值得用第二只手、值得多算一步」。对外仍是单 checkpoint、单 API。

**为什么是这个组合（可证伪的四条依据）**：

| 证据 / 结构 | 数值 / 来源 | 推出的设计 |
|---|---|---|
| 高双臂需求组平均成功率 23.49，低组 26.24；高组 oracle 33.09，低组 35.01 | teaser 缓存二次统计；人工先验，待 E619 | 双臂需求是一个真实的难度轴 → IP-10 角色 / 支撑臂 |
| 8 个模型中 7 个在高双臂组更差；Cliff's δ = −0.52 | 同上 | 不是单模型怪癖，而是任务结构 → 协作层有边际价值 |

## 2. 创新点详述

### IP-09 · CostLedger + ShadowPrice Allocator（P0）

- **动机**：v1 的 IP-01/02/03/04 都在增加模块，但没有统一的资源分配器。官方明确采集 per-step 延迟及其波动、动作统计规律性并可能据此评估可信度 ⇒ 「每个模块都开」既可能超预算，也可能把预算花在低边际相位。成本控制不是新的计分项，而是把有限的延迟 / 风险预算从低边际相位搬到高边际相位，最终必须体现在终态成功率上（v1 P1）。
- **与现有方案的差异**：多数提交只做「固定 chunk + 固定模块开关」；我们把成本做成**显式向量 + 影子价格**，用对偶上升在线调 `λ`，把「省一单位成本最多愿意损失多少成功点数」变成一个可解释、可审计的量。成本账本同时是可信度自证材料。
- **成本向量**：`C(o) = (ℓ, g, m, r, i)`：
  - `ℓ`：per-step 延迟（ms），硬预算，评测端直接观测；
  - `g`：算力（GPU ms / FLOPs 代理），影响 N 端口并发；
  - `m`：动作行程（关节位移 / 能量代理），影响干扰与磨损；
  - `r`：风险（碰撞 / 碰倒 / 滑移概率的代理分），影响硬失败；
  - `i`：干预次数（重抓 / 换手 / 非抓取原语），影响恢复成本与动作规律性。
- **预算**：`B = (B_ℓ, B_g, B_m, B_r, B_i)`，其中 `B_safe` 是不可挪用的安全储备（用于 v1 抓握确认、延迟兜底、碰撞保护）；任何可选模块只能花 `B − B_safe`。
- **技术可行性**：高。所有量都在本地可测；价值头可先用 v1 IP-06 的相位标签 + 规则先验，再升级为学习版；不需要新接口。
- **所需资源**：在线 <1 ms；离线价值 / 成本头 1×A100 × 数小时；无新数据。
- **落地步骤**：①定义成本向量与埋点；②实现账本（按端口隔离）；③规则版价值头（相位 × 选项的边际成功先验）；④对偶上升调 `λ`；⑤预算 sweep 画 Pareto；⑥导出审计报告；⑦与 v1 IP-03 的延迟兜底合并。
- **风险**：①成本模型标定错 ⇒ `λ` 把预算投到错误相位；②价值头在未见物体上漂移；③延迟测量噪声导致 `λ` 振荡。缓解：保守 `λ` 先验、`B_safe`、双时间尺度平滑、预注册 sweep、默认回退 v1 固定节拍。

### IP-10 · RoleToken SupportArm（P0）

- **动机**：高双臂需求组在 teaser 上更低（23.49 vs 26.24），且高组 oracle 也更低（33.09 vs 35.01）⇒ 这不是某个模型的问题，而是任务需要「第二只手提供约束」。v1 只有单臂抓握隐变量，无法表达「一只手稳住、一只手操作」。
- **与现有方案的差异**：不是「训练一个更大的双手策略」，也不是「两个独立策略投票」；而是**一个 checkpoint 内**用 role token 条件化左右动作头，并共享一个物体信念 `b_t`。第二臂优先做**被动支撑**（动态夹具），而不是一上来就做主动双手操作；这是成本最低、风险最小的协作形式。
- **角色定义**：`ρ_t = (ρ_L, ρ_R) ∈ {act, hold, idle}²`；同一时刻至多一个 `act`，除非 `z_phase ∈ {fold, zip, two_hand}`（形变 / 双手同步任务）。
- **共享物体信念**：`b_t = g_b(w_L, w_R, o_prop, a_{t−1})`，编码物体位姿 / 速度 / 抓握置信度 / 滑移概率 / 当前归属（谁在持物）。左右动作头与角色策略共享 `b_t`。
- **支撑臂生成**：给定物体 / 容器 / 接口的几何与任务相位，选择一个**约束位姿**（例如压住容器边缘、抵住接口底座、夹住织物一角），移动到接触位并保持；无触觉 ⇒ 用腕部视觉 + 小步位置修正，限制接触速度与保持力（关节位置目标的小刚度近似）。
- **技术可行性**：中–高。官方数据有左右臂 / 左右腕相机 / 左右抓手 / 左右 EE 位姿；角色可从运动学弱监督；支撑位姿可先用几何规则 + 数据检索，再学习。
- **所需资源**：数据 = 官方 32 数据集（≈32k eps）+ 自动角色标签；算力 = 8×A100 × 2–3 天（共享主干 + 左右头 + 角色头）；接口 = 无新增字段（仍输出左右 arm / gripper）。
- **落地步骤**：①RoleMiner 自动标注角色片段（IP-13）；②训练 role-conditioned BC 基线；③做「arm dropout」增强：训练时随机把一侧动作替换为 idle / hold，逼策略学会单臂与协作两种模式；④训练支撑位姿选择器；⑤加安全滤波（接触速度、行程、禁区）；⑥高双臂子集真机 A/B；⑦与 v1 IP-02 的抓握确认联动：换手 / 释放前先确认另一只手已抓住。
- **风险**：①角色标签噪声 ⇒ 双标注一致性 + VLM 抽检；②支撑臂干扰场景（碰倒别的物体）⇒ 禁区 + 低速 + 最大行程 + 默认 idle；③`control_space` 是全局的（joint / ee 二选一），不能给两只手不同空间 ⇒ 先实测，优先 joint 空间实现支撑保持；④双手同步数据稀缺 ⇒ 先用 arm dropout + 单臂数据，再补少量真机。

### IP-11 · HandoverEconomy（P1）

- **动机**：v1 的重抓是「放回桌面 / 重新接近」，成本高且会破坏已完成的阶段；如果第二只手能在空中接过去，恢复成本会显著下降。但换手有滑移 / 掉落风险，且需要协调延迟，所以必须**计价**，不能默认开启。
- **与现有方案的差异**：现有双手策略通常把换手当成一个隐式技能；我们把换手做成一个**显式选项**，与「原地重抓」「放回桌面重抓」比较期望恢复成本与成功率，只在 `HV > 0` 时启用。
- **换手协议**：
  1. 主动臂持物；支撑臂移动到接收位姿；
  2. 支撑臂闭合；用 v1 IP-02 的 `g_t` 确认 `g_support > τ_conf`；
  3. 主动臂张开；用共享信念确认物体仍稳定（无滑移 / 掉落）；
  4. 角色交换；若滑移 / 掉落风险超阈值，立即中止并用主动臂重新抓取。
- **约束**：只在 chunk 边界换手；每 episode 最多 2 次；换手前必须通过抓握确认；换手后必须重新估计 `b_t`；失败即回退到 in-place regrasp，再失败回退到 v1 table regrasp。
- **技术可行性**：中。官方数据中 handover 片段可能稀少 ⇒ 用角色转移 + 夹爪开合时序自动挖掘；不足时用合成 / 少量真机补。
- **所需资源**：数据 = 角色片段 + 少量真机；算力 = 小；接口 = 无。
- **落地步骤**：①从数据挖掘 handover 片段；②训练换手头 / 价值头；③实现协议与安全约束；④真机 A/B：handover vs in-place regrasp vs table regrasp；⑤报告恢复成本、成功率、滑移 / 掉落率。
- **风险**：①滑移 / 掉落 ⇒ 抓握确认 + 最大次数 + 中止回退；②协调延迟 ⇒ 只在块边界、低频；③数据稀缺 ⇒ 主动学习 + 合成；④换手可能被评测端视为「不规则交互」⇒ 保持动作平滑、记录审计。

### IP-12 · CompetenceGate（P0）

- **动机**：双臂 / 成本感知都是「放大器」：基座在插入 / 对齐上不够强时，第二只手可能让失败更体面却不更少，甚至主动干扰场景。v1 teaser 显示全体模型都卡在最后一环 ⇒ 必须有一个负结果保护。
- **与现有方案的差异**：多数方案默认「模块越多越好」；我们默认**全关**，只有满足能力、置信度、预期价值三个条件才开启。
- **闸门**：`G = 1[s_base ≥ s0 ∧ conf_ρ ≥ c0 ∧ E[VOC_support] > 0]`；`G=0` 时关闭主动 support / handover / two-hand，只保留 idle + v1 单臂策略。
- **技术可行性**：高。`s_base` 可用 v1 IP-06 代理评测 + episode 前段信号；`conf_ρ` 来自角色后验；`VOC` 来自 IP-09。
- **所需资源**：极小。
- **落地步骤**：①预注册 `s0 / c0`；②离线估计 `s_base`；③在线闸门 + 滞后；④负对照（打乱角色标签、随机支撑位姿、always-on / always-off）；⑤报告误开 / 误关。
- **风险**：①闸门太保守 ⇒ 错过收益；②太松 ⇒ 负迁移；③`VOC` 估计错 ⇒ 闸门失效。缓解：预注册阈值、双时间尺度、默认关、E626 负对照。

### IP-13 · RoleMiner（P1）

- **动机**：角色标签是 IP-10 的数据前置；人工逐帧标注 32k episodes 成本高，且「成本控制」也适用于**标注成本**。
- **与现有方案的差异**：用运动学弱监督 + VLM 抽检 + 主动学习，只标注最不确定的片段；把标注预算也纳入成本账本。
- **角色信号**：
  - `hold`：EE 位移小 + 抓手闭合 + 物体随另一臂运动；
  - `act`：EE 位移大 / 抓手开合变化 / 主动接近目标；
  - `idle`：EE 远离物体 / 未接触 / 长期静止；
  - `handover`：一侧张开 + 另一侧闭合 + 物体保持稳定 + 角色交换。
- **技术可行性**：高。信号全在官方数据里；VLM 只做 5% 抽检，成本可控。
- **所需资源**：数据 = 官方 32 数据集；算力 = 小；人工 = 抽检。
- **落地步骤**：①定义信号与阈值；②自动标注；③VLM / 人工抽检 5%；④双标注一致性；⑤主动学习补边界样本；⑥发布角色片段统计（高 / 低双臂组对比）。
- **风险**：①阈值在未见物体上漂移；②handover 片段稀少；③VLM 抽检偏差。缓解：多信号投票、置信度门控、与 E619 的高组 / 低组统计交叉验证。

### IP-14 · CostAudit（P2，审计部分并入 IP-09）

- **动机**：官方明示会采集 per-step 延迟及其波动、返回动作的统计规律性并可能据此评估可信度；在成功率接近时，可审计性是相对优势。
- **与现有方案的差异**：把「可信度」做成可导出的工程产物，而不是口头保证：成本账本、延迟直方图、干预 / 换手次数、风险事件、预算违规、降级次数、N 端口隔离报告。
- **技术可行性**：高（工程活）。
- **所需资源**：在线 <1 ms；离线脚本。
- **落地步骤**：①埋点；②按端口隔离账本；③导出 JSON / CSV；④N 端口 × 8 h 压测；⑤与 v1 IP-03 的审计合并。
- **风险**：①埋点开销 ⇒ 控制在 <1 ms；②过度平滑 / 限幅压低成功率 ⇒ 只作用残差；③「动作过于规律」被视为脚本化 ⇒ 保留策略固有随机性，不做人工拟人化噪声。

## 2.1 双臂需求的人工分组（预注册，待 E619 核验）

**规则**：若任务需要持续稳住物体 / 容器 / 接口，或双手同步维持形变 / 张紧，则记为「高」；若第二臂可提供有用支撑但非持续必需，记为「中」；若单臂 pick-and-place 已足够，记为「低」。分组在跑任何统计前写死，避免事后挑选。

- **高（12）**：Hang the Cup, Pack the Doll, Fold Towel, Zip Up, Open Pill Bottle, Syringe Water Transfer, Plug In Ethernet, Unlock, Arrange Test Tubes, Organize Stationery, Plug Charger, Paper Cup Stacking。
- **中（10）**：Pack Bag, Pack Phone, Store Racket, Toolbox Storage, Organize Bookshelf, Organize Pencil Case, Store Earphones, Place Photo Frames, Remove Pinned Note, Disconnect Ethernet。
- **低（10）**：Clear Plates, Color Arrangement, Conveyor Food Sorting, Fruit Basket Collection, Fruit Sorting, Organize Tools, Pick Out Battery, Spell robot, Stack Bowls, Stack Cups。

**统计结果（teaser 缓存，8 模型）**：

| 组别 | n | 平均成功率 | 跨模型 sd | per-task oracle | 平均时长 |
|---|---:|---:|---:|---:|---:|
| 高 | 12 | 23.49 | 6.42 | 33.09 | 45.10 s |
| 中 | 10 | 26.12 | 4.71 | 33.95 | 43.73 s |
| 低 | 10 | 26.24 | 5.49 | 35.01 | 44.15 s |

**效应量**：高 vs 低 Cliff's δ = −0.517（大）；高 vs 中+低 δ = −0.558。8 个模型中 7 个在高组更低，逐模型（低 − 高）差值范围为 −1.65（WALL-OSS-0.5）到 +7.21（GR00T N1.5）。

**必须核验**：E619 用官方数据自动挖掘角色片段，检验高组是否真的有更高比例的 `hold` / `handover` 片段；若没有，则本分组只是「任务难度」的代理，IP-10 降级为 P2，不能把难度差直接归因于双臂。

## 3. 符号与定义（U13–U24）

| 符号 | 含义 |
|---|---|
| `ρ_t = (ρ_L, ρ_R)` | 左右臂角色，∈ `{act, hold, idle}²` |
| `b_t` | 共享物体信念：位姿 / 速度 / 抓握置信度 / 滑移概率 / 归属 |
| `O` | 协作选项集 `{idle, support, act, handover, two_hand}` |
| `C(o)` | 成本向量 `(ℓ, g, m, r, i)`：延迟 / 算力 / 行程 / 风险 / 干预次数 |
| `B`, `B_safe` | 预算向量与不可挪用的安全储备 |
| `λ` | 影子价格（成功点数 / 单位成本） |
| `VOC(o)` | 协作选项价值 = `Δsuccess − λ·Δcost` |
| `SV_t` | 支撑臂边际成功增益 |
| `HV_t` | 换手相对重抓的净价值 |
| `s_base` | 基座（v1 单臂）成功率估计 |
| `G` | 能力闸门 ∈ {0,1} |
| `Λ` | 成本账本 / 审计证书 |

**定义 U13（角色分配）** `ρ_t = (ρ_{L,t}, ρ_{R,t}) ∈ {act, hold, idle}²`；约束「同一时刻至多一个 `act`」，除非 `z_phase ∈ {fold, zip, two_hand}`（任务显式要求双手同步）。
**定义 U14（共享物体信念）** `b_t = g_b(w_{L,t}, w_{R,t}, o_{prop,t}, a_{t−1})`，其中 `w` 为左右腕部特征，`o_prop` 为本体感受（EE 位姿 / 速度 / 抓手开合），`a_{t−1}` 为上一步动作；`b_t` 编码物体位姿、速度、抓握置信度、滑移概率、当前归属。
**定义 U15（协作选项）** `o_t ∈ O = {idle, support, act, handover, two_hand}`；`idle` 表示支撑臂保持当前位姿，`support` 表示移动到约束位姿并保持，`act` 表示支撑臂主动操作，`handover` 表示空中交接，`two_hand` 表示双手同步主动操作。
**定义 U16（成本向量）** `C(o) = (ℓ(o), g(o), m(o), r(o), i(o))`：`ℓ` 为 per-step 延迟（ms），`g` 为算力（GPU ms / FLOPs 代理），`m` 为动作行程（关节位移 / 能量代理），`r` 为风险（碰撞 / 碰倒 / 滑移概率的代理分），`i` 为干预次数。
**定义 U17（预算与安全储备）** `B = (B_ℓ, B_g, B_m, B_r, B_i)`，`B_safe` 为不可挪用的安全储备；选项 `o` 可行当且仅当 `C(o) ≤ B_remaining − B_safe`（逐分量）。
**定义 U18（影子价格与选项价值）** `λ = (λ_ℓ, λ_g, λ_m, λ_r, λ_i) ≥ 0`；`VOC(o|s) = ΔS(o|s) − λ·ΔC(o|s)`；运行时选 `o* = argmax_{o∈O, feasible} VOC(o|s)`；若 `max VOC ≤ 0`，取 `idle`。
**定义 U19（支撑臂边际价值）** `SV_t = P(success | support, b_t, z_phase) − P(success | idle, b_t, z_phase)`；用角色 dropout / 反事实增强离线估计，并在真机 A/B 校准。
**定义 U20（换手净价值）** `HV_t = [P(recover | handover) − P(recover | regrasp)] − λ·[C(handover) − C(regrasp)]`；仅当 `HV_t > 0` 且 `g_support > τ_conf` 且滑移风险低于阈值时换手。
**定义 U21（角色条件化策略）** `π(a_L, a_R | o, ℓ, z_task, z_phase, ρ_t, b_t) = h_{shared}(o, ℓ, z_task, z_phase, b_t) ∘ (h_L(·|ρ_L), h_R(·|ρ_R))`；`h_shared` 为共享主干，`h_L / h_R` 为左右动作头；整个 `π` 是一个 checkpoint。
**定义 U22（预算分配 / water-filling）** `B_j = argmax Σ_j ΔS_j(B_j)` s.t. `Σ_j B_j ≤ B`；在活跃相位上满足 `∂ΔS_j/∂B_j = λ`；若某些相位边际增益低于 `λ`，把预算搬到 align / insert / grasp 等高边际相位。
**定义 U23（能力闸门）** `G = 1[s_base ≥ s0 ∧ conf_ρ ≥ c0 ∧ E[VOC_support] > 0]`；`G=0` 时关闭主动 support / handover / two-hand，只保留 `idle` + v1 单臂策略。
**定义 U24（成本账本 / 审计证书）** `Λ = {(t, o_t, C_t, ρ_t, g_t, degraded_t)}`，按端口隔离；导出摘要包含延迟 p50/p99、算力、行程、风险事件、干预 / 换手次数、预算违规、降级次数、N 端口隔离结果。

        self.ledger.log(port, best, rho, b, a, t0)

```python
# ===== IP-09：成本账本 + 影子价格对偶上升 =====
class CostLedger:
    def __init__(self, tau_ms, lam0=(0.01, 0.001, 0.001, 0.05, 0.02)):
        self.tau_ms = tau_ms
        self.lam = np.array(lam0, dtype=np.float32)   # λ_ℓ, λ_g, λ_m, λ_r, λ_i
        self.budget = None                            # 每 episode 重置
        self.safe = None                              # B_safe：不可挪用

    def cost(self, o, obs, b):
        ell = self.predict_latency_ms(o, obs)         # 本地计时 / 小回归
        g   = self.predict_compute(o, obs)            # GPU ms 代理
        m   = self.joint_travel(o, obs)               # 关节行程
        r   = self.risk_score(o, obs, b)              # 碰撞 / 碰倒 / 滑移代理
        i   = 1.0 if o in (SUPPORT, HANDOVER, TWO_HAND) else 0.0
        return np.array([ell, g, m, r, i], dtype=np.float32)

    def feasible(self, o, obs, b, port):
        c = self.cost(o, obs, b)
        return bool(np.all(c <= self.remaining(port) - self.safe))

    def enforce(self, a, t0, port):
        elapsed = (time.perf_counter() - t0) * 1000.0
        if elapsed > self.tau_ms:
            a = safe_extend(a)                        # 末动作延拓 + 减速标记
            self.mark_degraded(port, elapsed)
        return a

    def dual_ascent(self, port):
        c_avg = self.episode_cost_avg(port)
        self.lam = np.maximum(0.0, self.lam + self.eta * (c_avg - self.budget))
```

# ===== IP-10 / IP-11：支撑位姿 + 换手协议（状态机） =====
class RolePolicy:
    def assign(self, option, b, phase, ztask):
        if option == IDLE:
            return (IDLE, IDLE) if self.active_side == LEFT else (IDLE, IDLE)
        if option == SUPPORT:
            # 选择非主动臂作为支撑臂；主动臂继续任务
            support = RIGHT if self.active_side == LEFT else LEFT
            return role_tuple(active=self.active_side, support=support)
        if option == HANDOVER:
            return role_tuple(active=self.active_side, support=other(self.active_side))
        if option == TWO_HAND:
            return (ACT, ACT)
        return role_tuple(active=self.active_side, support=IDLE)

class HandoverStateMachine:
    """只在 chunk 边界换手；最多 2 次；失败回退 in-place / table regrasp。"""
    def step(self, b, g_support, g_active):
        if self.state == "IDLE" and self.should_handover(b):
            self.state = "MOVE_SUPPORT"
        elif self.state == "MOVE_SUPPORT" and self.at_receive_pose(b):
            self.state = "CLOSE_SUPPORT"
        elif self.state == "CLOSE_SUPPORT" and g_support > TAU_CONF:
            self.state = "OPEN_ACTIVE"
        elif self.state == "OPEN_ACTIVE" and self.stable(b):
            self.state = "SWAP"
        elif self.state in ("CLOSE_SUPPORT", "OPEN_ACTIVE") and not self.safe(b):
            self.state = "ABORT_TO_REGRASP"
        return self.state

## 5. 推导（引理 L8–L14）

**引理 L8（支撑臂的约束价值）** 设任务需要同时满足 `m` 个独立接触约束；单夹爪最多提供 1 个抓握约束，环境最多提供 `e` 个外部约束。若 `m > 1+e`，单臂在原理上不可行；第二臂至少可再提供一个约束，故可行性条件变为 `m ≤ 2+e`。第二臂的边际价值为 `P(m > 1+e) − P(物体已被环境稳定)`。只有当该边际价值为正时，support 才值得它的成本。∎

**引理 L9（支撑臂降低干预阈值）** 设介入的期望收益为 `p·Δ`，成本为 `c`，影子价格为 `λ`；最优介入条件为 `p·Δ > λ·c`，即阈值 `p* = λc/Δ`。若 support arm 把恢复成本从 `c_R` 降到 `c_H < c_R`，且不降低恢复成功率，则 `p*_H < p*_R`，可介入的置信区间扩大；在 `p` 的分布不变时，期望成功率不降。**前提**：support 本身的成本 / 风险已计入 `c_H`，且 `c_H < c_R` 在目标相位成立。∎

**引理 L10（换手优于重抓的条件）** 设放回桌面重抓的期望成本 `c_R = c_transport + c_approach + c_grasp`，空中换手的期望成本 `c_H = c_coord + π_slip·L_slip`（`π_slip` 为滑移 / 掉落概率，`L_slip` 为失败损失）。若 `c_H < c_R` 且 `P(recover | handover) ≥ P(recover | regrasp)`，则换手的净价值 `HV > 0`。反之，若滑移损失或协调延迟过大，`HV ≤ 0`，应退回原地重抓。∎

**引理 L11（成本感知门控的阈值最优性）** 对二值决策「是否调用成本为 `c` 的选项」，设调用后的成功增益为 `Δ`，不调用为 0；在给定置信度 `p` 下，调用期望收益为 `pΔ − λc`。若 `p` 越大增益越大（单调似然比），则最优策略是阈值策略：`p > λc/Δ` 时调用。因此 `VOC > 0` 门控在二值选项下是 Bayes 最优的；多选项时取 `argmax VOC` 是逐状态贪心，若选项间无交互则全局最优，否则需加滞后 / 束搜索。∎

**引理 L12（跨相位预算的 water-filling）** 设终态成功近似为各相位成功概率之积 `P = ∏_j p_j(B_j)`，`B_j` 为相位 `j` 的预算，`p_j` 关于 `B_j` 凹且递增；总预算 `Σ B_j ≤ B`。拉格朗日条件下，活跃相位满足 `∂log p_j/∂B_j = λ`；边际增益低于 `λ` 的相位应被削减，预算搬到 align / insert / grasp 等高边际相位。若某相位已饱和（`∂p_j/∂B_j = 0`），不再投入。∎

**引理 L13（能力闸门的负迁移条件）** 把双臂成功率分解为 `P_dual = s_base + Δ_support − Δ_interference`。若 `s_base < s0`（基座太弱）或 `conf_ρ < c0`（角色估计不可信），则 `Δ_interference` 可能超过 `Δ_support`，出现负迁移。能力闸门 `G=1[ s_base ≥ s0 ∧ conf_ρ ≥ c0 ∧ E[VOC_support] > 0 ]` 是负迁移的**充分条件式**保护：它不保证一定正收益，但保证在三个必要条件不满足时不启用。∎

**引理 L14（降级链的可审计下界）** 若每个可选模块 `m` 都有一个可检测的失败条件和一个回退到 v1 的动作，且回退动作本身不依赖 `m`，则部署策略在任一模块失败时的行为等于 v1 加上「检测 / 回退」开销；因此成功率下界为 `P_v1 − ε_detect`，其中 `ε_detect` 为检测延迟导致的损失。成本账本记录每次降级，使该下界可审计。∎

| E634 | 每成功任务成本 / 每延迟成功率 | CPST 与 success per ms 可复现；相对 v1 无可信度回归 |

## 8. 预注册判据与处置

## 9. 风险登记册与剪枝预案

| 风险 | 概率 | 影响 | 对冲 |
|---|---|---|---|
| **成本模型标定错**：`λ` 把预算投到错误相位 | 中高 | 高（浪费预算 / 降成功率） | 保守 `λ` 先验、`B_safe`、双时间尺度平滑、E624/E625 预注册、默认回退固定节拍 |
| **角色标签噪声**：hold / act / handover 误标 | 中 | 中高 | 多信号投票 + VLM 抽检 5% + 双标注一致性；只在置信度高时启用 |
| **支撑臂干扰**：碰倒 / 推动其他物体 | 中高 | 高（硬失败） | 禁区 + 低速 + 最大行程 + 默认 idle + E620 干扰计数 |
| **换手滑移 / 掉落** | 中 | 高 | 换手前抓握确认、最多 2 次、块边界、失败回退 in-place / table regrasp |
| **动作空间语义**：`control_space` 全局二选一，支撑臂保持可能不如预期 | 中 | 中 | 先做 E627 零成本探测；优先 joint；必要时只用 ee |
| **合规**：双手 / 多专家被判「非单模型」 | 中 | 高（可能取消成绩） | 单 checkpoint、单 API、无外部编排；必要时书面确认；预备单臂降级形态 |
| **延迟**：协调头 + 价值头推高 p99 | 中 | 高 | 预算账本、头 ≤10 ms、降分辨率、关主动协作、v1 兜底 |
| **代理评测失真**：离线价值头与真机不一致 | 中 | 中高 | 沿用 v1 E601；E619/E620 真机锚点；|r|<0.3 即砍掉依赖代理指标的微调 |
| **过拟合 teaser**：按 teaser 数字调参 | 中 | 中 | teaser 是占位表；一切调参以 OOD 切分与真机 A/B 为准 |
| **数据稀缺**：handover / 双手同步片段少 | 中 | 中 | 角色转移挖掘 + arm dropout + 少量真机 + 主动学习 |
| **负迁移**：双臂在基座弱时更差 | 中高 | 高 | IP-12 闸门默认关；E626 负对照；未达标即回退 v1 |

**剪枝预案（下一轮起执行）**：

- **必保**：IP-06、IP-02、IP-03、IP-12（信息价值 + 机制正确性 + 负结果保护）。
- **优先深化**：IP-10（支撑臂，唯一直接针对高双臂组的结构性改动）、IP-09（成本账本，所有模块的公共计价器）。
- **条件推进**：IP-11（换手，依赖 E620/E621）、IP-13（角色挖掘，依赖 E619）。
- **暂存 / 合并**：IP-14 的审计并入 IP-09；IP-01 的合规确认仍按 v1 计划推进。
- **明确不砍**：v1 的 IP-06 / IP-02 / IP-03 是安全网；任何新模块失败都回退到它们。
