### 第 1 轮灵感驱动研究记录（通用平台 · MVP 视角）

**灵感词**：通用机器人平台、最小可行产品

**直觉与动机**：

前三轮（v26→v28）的主线是「不断加证书」：从 KEMPC 一路堆到九证一体的 KTCG，每轮都用更多证书去堵上一轮暴露的风险。这在单一双足机器人上是有效的，但它与两个新灵感词正面冲突：

1. **通用机器人平台**：如果双足、四足、轮式、机械臂各自都要一套定制的九证准入，平台就无法「通用」。真正的通用性不在于「支持所有证书」，而在于「用同一套最小内核，通过配置适配不同形态」。证书应当是可在形态间投影的算子，而不是形态特定的补丁。v28 的九证里，USMC 绑定双足支撑多边形、SSKL 绑定站立 COM 区间，这些是形态耦合的硬编码，天然排斥通用性。

2. **最小可行产品（MVP）**：v28 的九证在大多数任务上高度冗余——去掉其中几张，可执行集几乎不变，只是尾风险变大。MVP 的哲学是先找到「刚好够用」的最小证书基，把复杂度留给可选的扩展层，而不是把所有已知风险都硬编码成一张证书。证书越多，验证越慢、越难跨形态移植，也越容易在形态迁移时失真。

**关键洞见**：证书系统存在「基」的概念。九证不是九个独立约束，而是三个原始不变量在三类形态/任务语境下的投影：

- **准静态平衡不变量** `I_eq`：COM/ZMP 落在支撑域内且满足摩擦锥（USMC、SSKL 的投影）；
- **动态可达不变量** `I_reach`：存在预测时域内的可行控制序列且鲁棒裕度达标（KEMPC/KT-MPC、DCC、AKWA 的投影）；
- **语义/知识一致不变量** `I_sem`：当前形态下激活的知识规则及其解释/迁移全部成立（KC、IEKC、CTKTP、SMC、WLKB/TKP 的投影）。

找到最小生成基后，「通用平台」= 同一内核 + 平台配置 κ，「MVP」= 最小基 + 最小能力包（站立/行走/切换）。这同时缓解 v28 的两个隐患：证书膨胀（bloat）与形态耦合。

**形式化目标（增量）**：
1. 定义平台 `P = (M, S, A, f, E)`（形态、传感器、执行器、动力学、安全包络）与证书算子 `C: Π → {0,1}`，可执行集 `Adm(C) = {Π : C(Π)=1}`。
2. 定义证书基 `B = {C_1,…,C_k}`，`Adm(B) = ∩_i Adm(C_i)`；定义冗余与不可约：若 `Adm(B) = Adm(B\{C_j})` 则 `C_j` 冗余；无冗余成员的基为最小基。
3. 定义三原语内核 `UCK = {I_eq, I_reach, I_sem}`，并证明 v28 的九证均为其（在某平台配置下的）投影。
4. 定义 MVP 能力包 `π_MVP = {stand, walk, transition}` 与最小可行安全门 `MVG = Gate(UCK, κ, π_MVP)`。
5. 证明/实验：九证→三证的可执行集收缩 < ε（ε=1% 采样估计），跨 3 种形态仅改配置即可运行，单步延迟由 ~20ms 降至 ~8ms。

**本轮最大风险**：最小性是在「已观测任务分布」上度量的，而非真实分布；一个在训练任务上看似冗余的证书，可能正是某个罕见但致命失效模式（如切换瞬间打滑）的唯一防线，MVP 削减会静默删掉它，而通用平台会把这一缺口复制到所有机器人上——「最小可行」不等于「最小安全」。

## 0. 新增核心模块（在 v28 / IP-462~466 基础上做「减法重构」）

| 编号 | 名称 | 类型 | 关键改进（相对 v28） |
|---|---|---|---|
| IP-467 | Platform Profile & Abstraction Layer (PAL) | 平台抽象 | 用 `P = (M, S, A, f, E)` 描述任意形态；证书不再硬编码双足参数，而是读 `P`。支持双足/四足/轮式 |
| IP-468 | Certificate Basis Reducer (CBR) | 证书约简 | 以「可执行集消融」求最小证书基：移除某证书若不新增不安全计划且收缩 < ε，则判冗余 |
| IP-469 | Universal Certificate Kernel (UCK) | 安全内核 | 三原语 `{I_eq, I_reach, I_sem}`；证明 v28 九证均为其投影 |
| IP-470 | Minimal Viable Gate (MVG) | MVP 准入门 | `MVG = Gate(UCK, κ, π_MVP)`；只承诺最小能力包，可选扩展层后挂 |
| IP-471 | Certificate Compiler (CC) | 平台编译器 | 输入 `(P, 证书集合)`，自动约简 + 投影 + 生成该形态的 MVG；通用性 = 只换 `P` |

**产品定位（MVP v0.1）**：一个形态无关的安全内核 + 配置编译器，保证「站立/行走/切换」三类最小能力的安全准入；九证完整版、在线学习、跨任务迁移作为**非目标**留在扩展层。验收标准：三种形态仅改配置可跑通，双足安全指标不劣于 v28。

## 1. 增量符号体系（定义 1600–1699）

| 符号 | 含义 |
|---|---|
| `P = (M,S,A,f,E)` | 平台：形态 `M`、传感器集 `S`、执行器集 `A`、动力学 `f`、安全包络 `E` |

| `U(Π)` | 计划是否为不安全（ground-truth 标签） |
| `Δ_unsafe(B→B')` | 约简后新增的不安全可执行计划集合 |

## 2. 关键算法骨架

### IP-467 Platform Profile & Abstraction Layer

```python
@dataclass(frozen=True)
class PlatformProfile:
    morphology: str                 # "biped" | "quadruped" | "wheeled"
    sensors: dict                   # {name: rate_hz}
    actuators: dict                 # {name: (lo, hi)}
    dynamics_id: str                # 动力学模型指纹（文件哈希）
    safety_envelope: dict           # 形态特定边界：margin_min, mu, com_box ...
    capability_envelope: frozenset  # 该平台承诺的最小能力包

    def fingerprint(self) -> str:
        blob = json.dumps({
            "m": self.morphology, "s": sorted(self.sensors),
            "a": sorted(self.actuators), "d": self.dynamics_id,
            "e": sorted(self.safety_envelope),
        }, sort_keys=True).encode()
        return hashlib.sha1(blob).hexdigest()[:12]

    def support_polygon(self, contacts) -> list:
        # 形态无关：由接触点直接给出支撑多边形（双足=两脚，四足=四脚，轮式=轮接地）
        return convex_hull([c.xy for c in contacts])
```

要点：`support_polygon` 不再假设「双足两脚」，而是由接触集计算，这是形态解耦的关键。

### IP-468 Certificate Basis Reducer

```python
def reduce_basis(certs: list[CertificateOperator],
                 plans: list[RobotPlan],
                 profile: PlatformProfile,
                 eps: float = 0.01) -> list[CertificateOperator]:
    """贪心消融求最小基：移除证书若不新增不安全计划且收缩 <= eps，则冗余。"""
    full_adm = {p.id for p in plans
                if all(c.admits(p, profile) for c in certs)}
    basis = list(certs)
    changed = True
    while changed:
        changed = False
        for c in list(basis):
            trial = [x for x in basis if x is not c]
            trial_adm = {p.id for p in plans
                         if all(x.admits(p, profile) for x in trial)}
            added = trial_adm - full_adm
            unsafe_added = {pid for pid in added if LABELS[pid].is_unsafe}
            shrink_ok = len(added) / max(len(plans), 1) <= eps
            if not unsafe_added and shrink_ok:
                basis = trial            # c 冗余，移除
                changed = True
                break
    return basis
```

注意：`unsafe_added` 非空即拒绝移除——这是抵御「尾风险证书被误删」的第一道闸（见 R25）。

### IP-469 Universal Certificate Kernel

```python
class UniversalCertificateKernel:
    def __init__(self, profile: PlatformProfile):
        self.p = profile

    def I_eq(self, plan: RobotPlan) -> bool:
        """准静态平衡：COM 投影在支撑多边形内 + 摩擦锥 + 形态包络。"""
        com = plan.com(plan.t)
        poly = self.p.support_polygon(plan.contacts(plan.t))
        return (point_in_polygon(com, poly)
                and plan.friction_cone_ok(self.p.safety_envelope["mu"])
                and plan.inside_com_box(self.p.safety_envelope["com_box"]))

    def I_reach(self, plan: RobotPlan) -> bool:
        """动态可达：存在可行控制序列且鲁棒裕度达标。"""
        return (plan.mpc_feasible(self.p)
                and plan.robust_margin() >= self.p.safety_envelope["margin_min"])

    def I_sem(self, plan: RobotPlan) -> bool:
        """语义/知识一致：规则、解释、迁移在 P 下的投影全部成立。"""
        return all(rule.project(self.p).admits(plan) for rule in plan.kc_list)

    def admits(self, plan: RobotPlan) -> bool:
        return self.I_eq(plan) and self.I_reach(plan) and self.I_sem(plan)
```

**投影对应表（v28 九证 → UCK）**

| v28 证书 | UCK 原语 | 投影说明 |
|---|---|---|
| USMC 结构力学 | `I_eq` | 支撑多边形 + 关节力矩界 |
| SSKL 站立知识库 | `I_eq` | COM 盒 + 接触稳定 |
| SMC 语义地图 | `I_sem` | 地图语义规则 |
| WLKB/TKP 行走/切换知识 | `I_sem` | 形态无关规则投影 |
| IEKC 可解释证书 | `I_sem` | 解释=语义元数据 |
| CTKTP 跨任务迁移 | `I_sem` | 迁移=语义规则的 κ 投影 |
| KEMPC/KT-MPC 可行性 | `I_reach` | 预测时域可行 |
| DCC 动态一致性 | `I_reach` | 鲁棒裕度 |
| AKWA 自适应权重 | `I_reach` | 权重改变可行域边界 |

### IP-470 Minimal Viable Gate

```python
@dataclass
class MinimalViableGate:
    kernel: UniversalCertificateKernel
    profile: PlatformProfile
    capability_envelope: frozenset  # π_MVP = {"stand","walk","transition"}

    def admits(self, plan: RobotPlan) -> bool:
        if plan.mode not in self.capability_envelope:
            return False          # MVP 只承诺最小能力包，其余显式拒绝
        return self.kernel.admits(plan)
```

### IP-471 Certificate Compiler

```python
class CertificateCompiler:
    def __init__(self, sample_plans, labels, eps=0.01):
        self.plans, self.labels, self.eps = sample_plans, labels, eps

    def compile(self, profile: PlatformProfile,
                certs: list[CertificateOperator]) -> MinimalViableGate:
        basis = reduce_basis(certs, self.plans, profile, self.eps)
        prims = {c.projection() for c in basis}
        # 最小基必须覆盖三原语，否则说明样本不足/证书缺失
        if prims != {"I_eq", "I_reach", "I_sem"}:
            raise ValueError(f"基不完整: {prims}")
        return MinimalViableGate(
            UniversalCertificateKernel(profile),
            profile,
            profile.capability_envelope,
        )
```

通用性体现：换形态只换 `profile`；`compile` 自动约简出该形态的基，无需重写证书。

## 3. 复杂度分析（增量更新）

| 模块 | 时间复杂度 | 空间复杂度 | 关键参数 |
|---|---|---|---|
| PAL 支撑多边形 | O(n_c log n_c) | O(n_c) | n_c 接触点数 ≤ 4 |
| CBR 贪心消融 | O(k² · N_plan · k_cert) | O(N_plan) | k≤9, N_plan≈1e4 |
| UCK 三原语判定 | O(N_rule · H + n_x³) | O(N_rule + N) | H≤20, N_rule≤50 |
| MVG 准入 | O(N·n_x³ + N_rule·H) | O(N·n_x) | 仅一次 MPC 求解 |
| CC 编译 | O(k²·N_plan·k_cert)（离线） | O(N_plan) | 可离线预计算并缓存 |

**实时性**：v28 九证串行 ~20ms；UCK 三原语合并后关键路径仍是一次 MPC（5–15ms），语义/平衡判定 <2ms，总体 ~8ms，满足 50Hz。CBR 为离线编译，不占实时预算。

## 4. 正确性论证（增量更新）

### 引理 26（冗余移除保可执行集）
**陈述**：若 `Red(C_j, B)` 成立，则 `Adm(B) = Adm(B\{C_j})`。
**证明**：由冗余定义 `Adm(B)=Adm(B\{C_j})` 直接得。注意这一定义是集合层面的精确等价；CBR 用采样 `ε` 近似，故仅为「采样意义下」的等价，见 R25/R28。∎

### 引理 27（投影完备性）
**陈述**：对 v28 的每一张证书 `C`，存在 `I ∈ UCK` 与平台配置 `κ`，使 `C(Π) = I(Π; κ)` 对所有 `Π` 成立。
**证明**：按投影对应表逐一构造：`USMC/SSKL ↦ I_eq`（接触多边形与 COM 盒由 `κ` 给出）；`KEMPC/KT-MPC/DCC/AKWA ↦ I_reach`（可行性与裕度由 `κ.margin_min, κ.mu` 参数化）；`SMC/WLKB/TKP/IEKC/CTKTP ↦ I_sem`（规则集与迁移因子并入 `κ` 的规则投影）。每个 `C` 的判定式均可写成对应原语在特定 `κ` 下的实例化。∎

### 定理（MVG 的可靠性与最小充分性）
**陈述**：在能力包 `π_MVP` 内，(1) 可靠性：`MVG.admits(Π)=True ⇒ ¬U(Π)`（假定三原语对安全必要）；(2) 最小充分性：若 `B*` 最小，则移除任一原语 `I ∈ {I_eq,I_reach,I_sem}` 会使 `Adm` 严格扩大且存在 `Π` 使 `¬U(Π)` 被破坏。
**证明**：(1) 由 `admits` 为三原语合取，且每个原语都是对应安全条件的必要条件，合取成立则安全条件全满足。(2) 由 `B*` 不可约性，移除任一原语必使 `Adm` 严格扩大；若该原语对安全非空必要，则扩大的集合中必含不安全计划（否则该原语本可冗余，与最小性矛盾）。∎

> 注：定理 (1) 的可靠性依赖「三原语对安全必要」这一假设，正是 R25 的攻击面。

## 5. 实验设计

**E1 证书消融（9→k）**：在双足数据集（N≈1e4 采样计划，含正常/边界/打滑/切换）上跑 CBR，报告保留的基、可执行集收缩率、以及**留出尾集**（仅含罕见失效）上的不安全新增数。验收：收缩 ≤1% 且尾集不安全新增 = 0。

**E2 跨形态移植**：同一 UCK + 仅改 `profile`，分别跑双足（Cassie 类）、四足（Unitree 类）、轮式（差速底盘）。指标：配置改动行数（目标 <50 行/形态）、成功率、单步延迟。验收：三形态均能准入，配置仅涉 `safety_envelope` 与 `actuators`。

**E3 MVP 能力覆盖**：`π_MVP={stand,walk,transition}` 与完整能力集对比，报告成功率与违规率差。验收：最小能力包内指标与完整集差 ≤2%。

**E4 延迟基准**：v28 九证 vs MVG 三原语，各 1000 步统计 P50/P99 延迟。验收：P99 ≤ 10ms。

**E5 证伪实验（关键）**：人为从基中移除「仅对打滑切换有效」的规则，在打滑尾集上应出现显著违规上升。若上升不显著，则说明该证书确实冗余；若显著，则 CBR 的 `ε` 采样低估了尾风险，需引入尾集加权。

**统计口径**：所有「可执行集」结论基于采样估计，报告 95% 置信区间；尾集单独报告，不与主集混合平均。

## 6. 已知风险与缓解（增量更新）

| 风险编号 | 描述 | 严重度 | 缓解措施 | 剩余风险 |
|---|---|---|---|---|
| **R25** | **尾风险证书被误判冗余**：某证书只在罕见致命场景（打滑切换、极端负载）承重，主分布上看似冗余 | **高** | 1) CBR 的 `unsafe_added` 硬拒绝；2) 尾集重加权/对抗采样；3) 保留「廉价证书」白名单不参与消融 | 尾集本身采样不足时仍会漏判 |
| R26 | 平台抽象泄漏：`profile` 无法表达某形态特有约束，导致投影失真 | 高 | 1) `projection()` 接口强制声明形态前提；2) 编译期断言基覆盖三原语；3) 每形态独立回归测试 | 强耦合形态（如柔性/多臂）可能需扩展原语 |
| R27 | MVP 能力包边界蔓延：需求方不断加能力，MVP 名存实亡 | 中 | 1) 能力包冻结为 v0.1 契约；2) 扩展层独立门控；3) 变更需重新过 E3 | 商业压力下契约被突破 |
| R28 | 基约简过拟合采样：`Adm` 用有限样本估计，`ε` 阈值掩盖真实收缩 | 中 | 1) 报告置信区间；2) 主动采样边界/尾集；3) 保留最小基的「安全冗余证书」 | 高维状态空间采样覆盖仍不足 |

## 7. 本轮最大风险（最终确认）

**一句话**：**「最小可行」被误当成「最小安全」**——CBR 只在已观测分布上度量冗余，可能把仅在罕见致命失效（如切换瞬间打滑）中承重的证书判为冗余并删除；由于通用平台把同一内核复制到所有形态，这个被静默删掉的唯一防线会被同时移植到双足、四足与轮式，形成「处处通过、处处失守」的系统性盲区。
