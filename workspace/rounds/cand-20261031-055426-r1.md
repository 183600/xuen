# 第 13 轮（新循环第 1 轮）· TICK-SLAM：给 CHUNK-SERVO 的局部地图上发条——用本体惯性估计隐藏延迟，用稀疏关键帧记住目标，用 anytime 分层守住轻量

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新灵感循环第 1 轮，研究线承接第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO；并行候选里的 PSALM（对象级记忆）和 ANCHOR-ICP（腰部运动学 + 双目配准）已经把“桌面局部地图”证明了一半。三个灵感词是「同步定位与建图」「惯性测量单元」「轻量化设计」。本轮不推倒 CHUNK-SERVO 的“30 步规划 + 5 步伺服”，而是补它最容易被忽略的一层：**伺服不只需要更快，还需要知道“这张图是什么时候的、目标在遮挡期间去哪了、下一次执行时它会在哪”。**

## 0. 先给结论：167ms 的闭环，可能被一个没建模的 100ms 延迟吃掉

第 12 轮把反馈周期从 1 秒压到 167ms，这是对的。但它有一个隐含假设：**观测、本体状态和动作执行共享同一个时钟，而且目标位姿是当前帧的确定函数。**

真实系统里至少有三件事不成立：

1. **延迟不是一个数，而是三个时钟的差。** 图像采集、本体状态采样、动作下发/执行各有一条时间线；API 没有给 timestamp（本轮复核提交 README，观测字段里没有 timestamp），网络 RTT 也不等于“动作到观测”的端到端延迟。若实际延迟比假设多 50–150ms，夹爪以 10cm/s 接近时，最后 3cm 内就会多走 5–15mm——正好是插入/挂杯/拉链/开锁的误差量级。
2. **目标位姿没有记忆。** 第 12 轮每帧重新估计 `T_base_target(t)`；一旦夹爪/手臂遮挡目标、或人手把目标挪走，估计会跳变。单帧估计没有“目标刚才在哪、这次跳变是遮挡还是真的被移动”的假设检验。
3. **单帧双目在 0.5m 的深度误差是十几毫米，不是毫米。** 头双目基线 58.25mm、焦距约 282px；1px 视差在 0.5m 处约 15mm。最后 1–2mm 必须靠腕部近距（0.1m 处 1px≈0.23mm）和已知目标模板；而腕部相机的手眼外参，数据集里没有。

所以本轮的押注是 **TICK-SLAM**：

> **用腰部/手臂运动学构造一个“本体惯性源”（KIN-IMU），用它和图像运动的互相关在线估计隐藏延迟；用一张目标中心、稀疏关键帧、可回环重定位的桌面局部地图，记住目标跨遮挡的位姿；用 anytime 分层把地图压到每端口 <10ms/<200MB，并让 VLA 只在语义变化时重规划。**

一句话：**第 12 轮把“看”变成了“每 167ms 看一次”；本轮要回答“这一次看到的是什么时候的世界、上次看到的目标还在不在、下次动作执行时它会在哪”。**

三个可验证创新点：

1. **TICK 时间校准**：用腕部/头部图像流与本体 EE/腰部 twist 的互相关，估计传感器时差 `τ_s` 与动作-观测延迟 `τ_a`；在 1kHz 插值下，合成实验可把 33–200ms 延迟恢复到 1ms 分辨率。验证：G9。
2. **目标中心局部 SLAM**：离线用 33k 成功演示重建目标稀疏模板；在线用关键帧 + 目标 landmarks + 回环/变化点，跨遮挡维护 `T_MT(t)` 与协方差；不是房间尺度 SLAM。验证：G8/G12。
3. **Anytime 轻量分层**：Tier 0（CHUNK-SERVO）/ Tier 1（EKF 目标跟踪 + 时间校准）/ Tier 2（固定滞后 BA + 回环）；后台异步、查询 O(1)、按 CPU/不确定性升降级。验证：G10/G11。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **同步定位与建图** | 目标中心局部地图：关键帧、目标 landmarks、回环重定位、变化点；用多视图压低深度噪声 | 不做房间尺度/稠密 SLAM；不做 NeRF/3DGS；不建全桌语义图 |
| **惯性测量单元** | KIN-IMU：waist FK + EE 位姿 + 有限差分 twist；有 raw IMU 就换成预积分；用于传播、预测、时差校准 | 不伪造 IMU 数据；不假设 API 暴露 IMU；不把 IMU 塞进 VLA 输入 |
| **轻量化设计** | 稀疏 landmarks + ROI + 固定滞后 + 事件触发 BA + 异步后台 + anytime 分层；CPU-only | 不压缩/重训 6B；不加第二个学习模型；不做 30Hz 全图 SLAM |

## 1. 这轮怎么想：三个词是一条“时间—记忆—预算”的因果链

### 1.1 SLAM：桌面任务需要的不是地图，是“目标的短期记忆”

第 12 轮的伺服把目标位姿写成一个当前帧函数：`T_base_target(t) = f(images_t)`。这在目标一直可见、相机不动、没有遮挡时成立。但最后 3 厘米恰恰是目标最容易被夹爪、手腕、另一只手臂挡住的时刻；而人为干扰轴（20% 的试次）会直接把目标挪走。

桌面任务不需要建整间房，也不需要稠密点云。它需要一张**目标中心的局部地图**：

- **关键帧**：记录目标清晰可见的若干时刻的相机位姿、目标位姿和图像 ROI；
- **目标 landmarks**：目标/受器上 20–40 个稀疏点，来自成功演示的多视图三角化；
- **回环**：目标被遮挡后重新出现时，用 ROI 描述子匹配到旧关键帧，用 PnP 给出相对位姿，把新旧观测接起来；
- **变化点**：如果匹配到的目标位姿和旧地图不一致，不要硬接；先判断“同一目标被移动”还是“换了一个物体”，再决定更新地图还是请求 VLA 重规划。

这张地图解决四件事：遮挡期间保持目标位姿；多视图降低深度噪声；人手移动目标后重定位；给伺服一个带协方差的、可查询的未来位姿。它不解决透明/反光/变形的感知极限——那些仍然靠腕部近距和回退。

**与 PSALM/ANCHOR-ICP 的差别**：PSALM 做的是对象级长期记忆，ANCHOR-ICP 做的是米制场景图 + 双目配准；它们都没有把“时间对齐”作为地图的一等状态，也没有把地图查询接到 5 步伺服的执行时刻上。TICK-SLAM 只做这一层增量：**地图不是“物体在哪”，而是“在时刻 t+τ，目标相对夹爪应该在哪”。**

### 1.2 IMU：API 里没有 IMU，但有一个可用的“本体惯性源”

本轮复核提交 README：观测里没有 IMU、没有 timestamp、没有 depth。所以不能写“用 IMU 做预积分”这种假设。正确做法是把**本体运动学**当成一个低带宽惯性源：

- 头部相机位姿 `T_BH(q_t)` 由腰关节 `lower_body[-3:]` + URDF 正运动学重建；底座固定时 `T_MH = T_MB · T_BH`；底座动了就把 `pivot` 积分进 `T_MB`。
- EE 位姿 `T_BE(t)` 由 API 直接给。
- 对两者做有限差分，得到头部/EE 的 twist；用关节编码器噪声和差分加速度噪声给协方差。
- 如果未来 API 暴露 raw IMU，或机器人内部能拿到 IMU，就把同一接口换成预积分因子；算法不变。

这个 KIN-IMU 的第一用途不是“给 VLA 多一路输入”，而是**估计时间**：

> 如果相机和本体观测的是同一个刚体运动，那么图像里的背景光流和本体 twist 在时间上应对齐；对齐的偏移量就是传感器时差 `τ_s`。同理，命令的 EE 运动和图像里观测到的 EE 运动之间的偏移，给出动作-观测延迟 `τ_a`。

这不是新数学（VINS 的 temporal calibration 早就这么做），新的是**把它用在远程 API 的隐藏延迟上**，并且只用机器人自己的自然运动，不需要额外传感器。

#### 本轮的数据探针：手腕比腰部更适合做时间校准

我在 HangCup 的前 500 行（3 个 episode）上做了两个小实验（详见产物区 §1.6）：

- **头/腰自然运动**：单个 episode 7.1s，腰 yaw 范围只有 **0.031 rad**，最大角速度 **0.139 rad/s**，中位 `|ω|` 约 **0.009 rad/s**、均值约 **0.018 rad/s**。折算到 30Hz、f≈282px，峰值约 **1.3 px/帧**，多数时间 **<0.2 px/帧**。这只能做“机会式”校准，不能支撑连续 τ 估计。
- **腕/臂运动**：同一 episode，左 EE 速度中位数 **3.3 cm/s**、峰值 **0.49 m/s**；右 EE 中位数 **7.0 cm/s**、峰值 **0.67 m/s**；60–83% 的时间速度 >2cm/s。腕部相机在 0.1m 处 1mm 位移约 **4.4 px**，在 0.3m 处约 **1.5 px**。**自然抓取运动本身就是很强的激励源。**

所以 TICK-SLAM 的时间校准主通道是**腕部相机 vs EE 命令**，头部/腰部只做辅助；如果一开始手臂不动，就先不估计 τ，用保守先验，等第一次 reach 再收敛。这个设计选择是被数据逼出来的，不是拍脑袋。

另一个探针：把腰 yaw 当作“视觉信号”的合成代理，注入 33/66/100/150/200ms 延迟和噪声，再用 1kHz 插值做互相关；五个延迟全部恢复到 **1ms** 分辨率（产物区 §1.6）。这证明估计器的数值行为，不证明真实图像上的可观测性——真实可观测性要靠 G9。

### 1.3 轻量化：不是把 6B 压小，而是把新增层压到“可忽略”

第 12 轮已经决定用官方 WLA 基座，不从零训大模型。所以“轻量化设计”在本轮不是模型压缩，而是**新增几何层的预算纪律**：

- **稀疏**：20–40 个目标 landmarks、5–8 个关键帧，不建稠密图；
- **ROI**：只在目标/桌面局部提特征，不处理全图；
- **固定滞后**：只优化最近 5–8 个关键帧，旧状态边缘化；
- **事件触发**：只在关键帧或 NIS 报警时跑 BA/回环，不是每帧；
- **异步**：重 BA 在后台线程；`get_action` 只读最新地图状态并做 O(1) 查询，绝不阻塞；
- **anytime**：Tier 0/1/2 按任务、相位、CPU 负载升降级；地图挂了，CHUNK-SERVO 照常工作；
- **VLA 门控**：几何变化（目标动了但还是同一个物体）由伺服处理，不重规划；只有语义变化才请求 VLA，减少 GPU 调用。

目标预算：每端口 Tier 2 平均 **<10ms/帧**、峰值 **<20ms**，内存 **<200MB**，CPU-only，不抢 GPU。这个预算必须由 G10 实测，不靠估计。

## 2. 关键事实与修正（只列会改变方案的）

### 2.1 API：四路 RGB、无 depth/IMU/timestamp，chunk 固定

沿用第 12 轮已核实的提交 README，本轮补两条负面事实：

- 观测键里**没有 timestamp**；不能假设能拿到图像/本体的采集时间戳。
- 观测键里**没有 IMU**；不能假设能拿到角速度/加速度。
- `action_chunk_size` 固定，chunk 内无新观测、无打断；N 端口从 8765 起，每端口独立。

**推论**：时间校准必须从“运动本身”估计，不能依赖 API 时间戳；惯性必须先由运动学构造。若未来 API 增加 timestamp/IMU，TICK-SLAM 的接口不变，只是把估计器换成更高带宽的版本。

### 2.2 数据：腕部 color 有内参，缺的是手眼；头部双目已标定

第 12 轮写“腕部相机没有内参矩阵”，本轮复核 HangCup 的 `meta/info.json` 后修正：

- 腕部 color **有内参**：左 `fx=436.406, fy=435.922, cx=323.922, cy=242.933`；右 `fx=435.115, fy=434.499, cx=319.025, cy=240.993`；畸变模型是 inverse Brown-Conrady。
- 缺的是**腕部相机到 EE 的手眼外参 `T_EW`**，不是内参。手眼可以一次性棋盘格标定，也可以在线用目标/桌面 landmarks  refine。
- 头部双目：`fx≈282.37/281.87`，基线 **58.2526mm**，`rectified: true`；左右主点差 18.4px/7.1px，不能默认严格行对齐，要先做对极校正验证。

**推论**：腕部 2D 因子可以直接用已知 `K_W`；最后 1–2mm 的深度不是靠“腕部单目猜深度”，而是靠**已知目标 3D 模板的 PnP**（模板给尺度），头双目给独立尺度校验。手眼外参是 G0 的第一项。

### 2.3 头相机位姿可以从腰关节重建（离线探针已验证）

在 HangCup 前 30 帧上验证：

- `state_torso.rpy` 与 `waist_state_joint` 的 `[roll, pitch, yaw]` 只差一个近常数偏移：约 `[6e-5, 1e-6, 6.8e-4] rad`；
- `T_torso_d435 = inv(T_base_torso) · T_base_d435` 的平移为 `[0.057624, 0.017530, 0.429870] m`，旋转约 `pitch=0.830777 rad`；
- 30 帧内该相对变换的变化 <`2e-8 m` / `1.4e-7`（旋转矩阵范数）。

**推论**：在线只要 `lower_body[-3:]` + 固定安装变换，就能重建头部相机位姿；这就是 KIN-IMU 的地基。它不是 IMU，但它提供了和 IMU 一样的“自运动先验”，而且没有额外传感器假设。

### 2.4 单帧双目深度不够，多视图 + 腕部近距才够

头双目深度误差：

| 工作距离 Z | 1px 视差 → 深度误差 | 0.1px 亚像素 → 深度误差 |
|---:|---:|---:|
| 0.3 m | 5.5 mm | 0.55 mm |
| 0.5 m | 15.2 mm | 1.52 mm |
| 0.8 m | 38.9 mm | 3.89 mm |
| 1.0 m | 60.6 mm | 6.06 mm |

单帧 1px 误差在 0.5m 就是 15mm，不能支撑最后 1–2mm。局部 SLAM 的价值是：多关键帧对同一 landmark 做三角化，噪声按 `1/√N` 降；小范围腰部/头部运动提供额外基线；腕部在 0.1m 处提供 0.23mm/px 的横向分辨率，并用已知目标模板 PnP 给深度。三者互补，而不是互相替代。

### 2.5 延迟要拆成 `τ_s + τ_a`，RTT 只是其中一部分

定义：

- `τ_s`：图像采集与本体采样之间的时差（sensor skew）；
- `τ_a`：动作下发到下一次观测之间、超出 chunk 执行时间的额外延迟（RTT + 编码/解码 + 推理队列 + 执行器）；
- `τ = τ_s + τ_a`。

第 12 轮用“测 RTT + Smith 预测”处理延迟，但网络层 RTT 不包含图像编码/解码、推理排队、执行器响应，也不包含观测与本体之间的采样偏移。TICK-SLAM 用运动互相关直接估计端到端等效 `τ`，再用它查询地图。估计不出来时，用保守上界并把协方差放大；不要假装知道。

## 3. TICK-SLAM 一页纸

### 3.1 架构

```text
Evaluator (N ports)
   │ websocket obs / action chunk
   ▼
Per-port PolicyService (CPU)
   ├─ CHUNK-SERVO: VLA 30-step plan + 5-step servo
   ├─ TICK-SLAM
   │   ├─ KIN-IMU: waist FK + EE pose → twist, covariance
   │   ├─ TimeCal: wrist/head flow ↔ EE/waist twist → τ_s, τ_a
   │   ├─ TargetMap: keyframes + target landmarks + PnP/stereo factors
   │   ├─ LoopClosure: target ROI match → loop factor / change point
   │   └─ Query(t+τ): target pose + covariance + validity
   └─ VLA gate: geometric change → servo; semantic change → replan
   │
   ▼ async
Shared VLA server (GPU, 30-step plan)
```

### 3.2 形式化核心

坐标系：`M` 地图系（桌面锚定）、`B` 底座、`H` 头左目、`W` 腕部、`E` EE、`T` 目标/受器。

状态（Tier 1 EKF）：

```math
\mathbf x_t = \left(T_{MH_t},\ \xi^H_t,\ T_{MT_t},\ \xi^T_t,\ \tau\right)
```

Tier 2 固定滞后 MAP：

```math
\min_{\mathcal X,\mathcal L}\ 
\sum_{\text{prop}}\|r_{\text{prop}}\|^2_{\Sigma_p}
+\sum_{\text{stereo}}\rho(\|r_{\text{stereo}}\|^2_{\Sigma_s})
+\sum_{\text{wrist}}\rho(\|r_{\text{wrist}}\|^2_{\Sigma_w})
+\sum_{\text{loop}}\rho(\|r_{\text{loop}}\|^2_{\Sigma_l})
+\sum_{\text{rigid}}\rho(\|r_{\text{rigid}}\|^2_{\Sigma_c})
```

输出给伺服：

```math
\hat T_{MT}(t+\hat\tau)=\hat T_{MT}(t)\exp(\hat\tau\hat\xi^T_t),
\qquad
\Sigma_T(t+\hat\tau)=\Sigma_T(t)+\hat\tau^2\Sigma_{\xi^T}+Q_\tau
```

伺服把 `T_BT = T_BM · T_MT` 代进第 12 轮的相对目标误差，增益按 `Σ_T` 和 `τ` 降档；地图失效就回退 CHUNK-SERVO。

### 3.3 三个关键机制

**TICK 时间校准**：

- 腕部图像背景光流 `f_t` ↔ EE twist `ξ^E_t`；头部图像背景光流 ↔ 头部 twist `ξ^H_t`。
- 一维搜索 `τ`，最小化鲁棒重投影/光流残差；1kHz 插值 + 抛物线峰值细化。
- 只在激励足够（速度/角速度、inlier、图像梯度）时更新；否则保持先验并膨胀协方差。
- 输出 `τ̂` 与置信度；伺服预测和增益调度都用它。

**目标中心局部 SLAM**：

- 离线：33k 成功演示 → 每个任务的目标稀疏模板 `{(p_j^T, descriptor_j)}` + 关键帧 ROI 库。
- 在线：头部双目 + 腕部 PnP 初始化 `T_MT`；关键帧选择（位移 >1cm、旋转 >2°、ROI 重叠 <60%、0.5s）；固定滞后 BA。
- 回环：目标重新出现时，ROI 描述子匹配旧关键帧 → PnP → 回环因子；inlier ≥15、重投影 ≤3px 才接受。
- 变化点：NIS/CUSUM 持续报警 → 判断“同一目标被移动”还是“换了物体”；前者新建目标节点，后者请求 VLA。

**Anytime 轻量分层**：

- Tier 0：CHUNK-SERVO；无地图。
- Tier 1：EKF 目标跟踪 + 时间校准；默认所有 A 档任务。

## 7. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 目标刚性静止假设 | 人移动目标后回环接错，自信追错 | 变化点检测 + 几何/外观双重验证；不确定就停/回退 |
| 无 raw IMU/timestamp | 时间校准退化 | 腕部自然运动激励强；机会式更新 + 保守先验；G9 门控 |
| 腕部手眼缺失 | PnP/伺服偏差 | 一次性棋盘格 + 在线 refine；头双目独立校验 |
| 透明/反光/变形 | 特征/深度失效 | 只对刚体任务启用 Tier 2；ROI/边缘/腕部近距；回退 |
| 回环误匹配 | 地图污染 | inlier/重投影/时序一致性三重门；误匹配不更新 |
| 计算超预算 | p99 上升 | 异步 + anytime + 事件触发；G10 硬门 |
| VLA 计划与地图冲突 | 伺服和规划打架 | 几何变化归伺服，语义变化归 VLA；限幅 + 仲裁 |
| 单模型解释 | 被判第二个模型 | 确定性几何/控制，无学习权重；C2 合规说明 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |

## 8. 一句话押注与最大风险

**一句话押注**：把 CHUNK-SERVO 的“每 167ms 看一次”升级为“每 167ms 看一次，而且知道这张图的时间、目标的历史、下一次执行时目标的位置”；用 KIN-IMU 估延迟，用目标中心局部 SLAM 记住遮挡，用 anytime 分层守住 CPU。

**最大风险**：TICK-SLAM 把“目标在两次观测之间刚性静止”写进了地图先验；一旦人手在遮挡窗口内移动目标，回环可能把新位姿错误地接回旧地图，系统会比开环更自信地追错目标。所以本轮的第一道门不是地图精度，而是**变化点检测的误报率**。

> 检索/复核日期：**2026-10-31（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「TICK-SLAM」的工程化产物；不替换第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO，而是给 CHUNK-SERVO 补上“时间对齐 + 目标记忆 + 轻量预算”这一层。

## 0. 结论与边界

### 0.1 一句话结论

CHUNK-SERVO 把反馈周期从 1s 降到 167ms，但闭环的质量还取决于两件没有建模的事：**观测是什么时候的**，以及**目标在遮挡/人扰期间去哪了**。TICK-SLAM 用腰部/手臂运动学构造 KIN-IMU，用图像运动与本体运动的互相关估计隐藏延迟 `τ`；用目标中心、稀疏关键帧、可回环重定位的桌面局部地图维护 `T_MT(t)` 与协方差；用 anytime 分层把新增层压到每端口 <10ms/<200MB，CPU-only；地图失效时严格回退 CHUNK-SERVO。

## 1. 事实核对与离线探针

### 1.1 规则与 API（A）

沿用第 12 轮已核实的官方规则：32 任务、每任务 10 次、5 类泛化各 2 次、单次 180s、单模型、N 端口 8765 起、每端口独立 reset、有不计分的单任务通道。提交 README 的动作/观测契约不变：四路 RGB 480×640；双臂关节/EE、夹爪、`lower_body[15]`、语言；`control_space` 仅 `joint` 或 `ee`；`action_chunk_size` 固定；chunk 内无新观测、无打断；无 depth/force/tactile。

本轮复核 README 补两条**负面事实**（A）：

1. 观测键里**没有 timestamp**。不能依赖 API 给出图像/本体的采集时间。
2. 观测键里**没有 IMU**（角速度/加速度/重力）。不能假设有 raw inertial measurement。

**对方案的约束**：时间校准必须从“运动本身”估计；惯性必须先由运动学构造。若未来 API 增加 timestamp/IMU，TICK-SLAM 的接口不变，只把估计器换成更高带宽版本。

### 1.2 数据与相机（A，含一处第 12 轮修正）

32 个 HF 数据集合计 **33,276 episodes / 18,282,246 frames / 169.28 h / 30 fps**；单任务 969–1,533 集。HangCup 的 `meta/info.json` 复核：

- 头部双目：`fx≈282.369/281.874`，`fy≈282.752/282.319`，基线 `T=[-58.2526, -0.1675, 0.5786] mm`，`rectified: true`。左右主点差 18.4px/7.1px，不能默认严格行对齐，先验证对极误差 ≤1px。
- **腕部 color 有内参**（修正第 12 轮“腕部没有内参”的说法）：左 `fx=436.406, fy=435.922, cx=323.922, cy=242.933`；右 `fx=435.115, fy=434.499, cx=319.025, cy=240.993`；模型 `distortion.inverse_brown_conrady`。
- 缺的是**腕部相机到 EE 的手眼外参 `T_EW`**，不是内参。手眼可以一次性棋盘格标定，也可以在线用目标/桌面 landmarks refine。
- 数据集有 `timestamp [1]`、`state_torso`、`state_d435`；在线 API 只给 `lower_body` 和 EE，因此头部相机位姿要靠腰关节 FK 重建。
- 数据里 `action.pivot` 在桌面任务中近乎常数（第 10/12 轮已审计）；本报告默认底座固定，若 `pivot` 动了就把命令积分进 `T_MB`。

### 1.3 离线探针 P0：头相机位姿可从腰关节重建（B）

在 HangCup 前 30 帧上，用 `state_torso` 和 `state_d435` 做核对：

```text
T_torso_d435 = inv(T_base_torso) · T_base_d435
平移 = [0.057624, 0.017530, 0.429870] m
旋转 ≈ pitch 0.830777 rad
30 帧内平移变化 < 2e-8 m；旋转矩阵变化 < 1.4e-7（Frobenius）
state_torso.rpy 与 waist_state_joint 的 [roll,pitch,yaw]
只差近常数偏移 ≈ [6e-5, 1e-6, 6.8e-4] rad
```

**结论**：在线只要 `lower_body[-3:]` + 固定安装变换，就能重建头部相机位姿。这个探针只在 HangCup 的 30 帧上做，G0 要在 32 任务、多台机器人上复核固定变换是否一致；不一致就每台机器人标定一次。

### 1.4 深度误差（B）

头双目深度误差：

```math
\frac{\partial Z}{\partial d}=-\frac{Z^2}{f b},
\qquad f\approx282.37\text{ px},\ b=0.0582526\text{ m}.
```

| 工作距离 Z | 1px 视差 → 深度误差 | 0.1px 亚像素 → 深度误差 |
|---:|---:|---:|
| 0.3 m | 5.5 mm | 0.55 mm |
| 0.5 m | 15.2 mm | 1.52 mm |
| 0.8 m | 38.9 mm | 3.89 mm |
| 1.0 m | 60.6 mm | 6.06 mm |

**含义**：单帧双目在 0.5m 的 1px 误差就是 15mm，不能支撑最后 1–2mm。局部 SLAM 的多关键帧三角化把噪声按 `1/√N` 降；小范围腰部/头部运动提供额外基线；腕部在 0.1m 处提供 0.23mm/px 的横向分辨率，并用已知目标模板 PnP 给深度。三者互补。

### 1.5 延迟分解（C，基于 A 的接口事实）

定义：

- `τ_s`：图像采集与本体采样之间的时差（sensor skew）；
- `τ_a`：动作下发到下一次观测之间、超出 chunk 执行时间的额外延迟（RTT + 图像编码/解码 + 推理排队 + 执行器）；
- `τ = τ_s + τ_a`。

反馈周期：

```math
T_{\mathrm{fb}} = \frac{H_c}{f_c} + \tau.
```

第 12 轮用“测 RTT + Smith 预测”处理延迟，但网络层 RTT 不包含图像编解码、推理排队、执行器响应，也不包含观测与本体之间的采样偏移；API 又没有 timestamp。所以必须从运动本身估计 `τ`，估计不出来时用保守上界并放大协方差。

### 1.6 离线探针 P1/P2：时间校准的激励与数值行为（B）

#### P1：自然运动激励

取 HangCup 前 500 行（3 个 episode），选最长 episode（episode 0，214 帧，7.1s，30Hz）：

| 信号 | 统计 | 折算到图像 |
|---|---|---|
| 腰 yaw | 范围 0.031 rad；中位角速度 ≈0.009 rad/s；均值 ≈0.018 rad/s；峰值 0.139 rad/s | 中位 ≈0.08 px/帧；均值 ≈0.17 px/帧；峰值 ≈1.3 px/帧（f≈282） |
| 左 EE 速度 | 范围 `[0.067, 0.242, 0.137] m`；中位 3.3 cm/s；峰值 0.49 m/s；59.6% 时间 >2cm/s | 0.1m 处 1mm≈4.4px；中位 ≈4.8 px/帧 |
| 右 EE 速度 | 中位 7.0 cm/s；峰值 0.67 m/s；83.1% 时间 >2cm/s | 0.1m 处中位 ≈10 px/帧 |

**结论**：头部/腰部的自然运动多数时间只有 <0.2px/帧，不能支撑连续 `τ` 估计；腕部/手臂的自然 reach 运动是强激励源。TICK-SLAM 的时间校准主通道是**腕部相机 vs EE 命令**，头部/腰部只做辅助。若一开始手臂不动，就先不估计 `τ`，用保守先验，等第一次 reach 再收敛。

#### P2：合成延迟恢复

把腰 yaw 当成“视觉信号”的合成代理，注入 33/66/100/150/200ms 延迟和 15% 噪声，用 1kHz 插值 + 互相关搜索：

| 注入延迟 | 估计延迟 | 相关系数 |
|---:|---:|---:|
| 33 ms | 33 ms | 0.989 |
| 66 ms | 66 ms | 0.989 |
| 100 ms | 100 ms | 0.989 |
| 150 ms | 150 ms | 0.990 |
| 200 ms | 200 ms | 0.990 |

**边界**：这是合成代理，只证明估计器的数值行为（1kHz 插值可到 1ms 分辨率），不证明真实图像上的可观测性。真实可观测性必须用腕部/头部视频 + 真实光流在 G9 验证。合成实验也说明：如果信号是周期性的，互相关会有多峰；需要用宽带/自然 reach 或短扫描打破歧义。

### 1.7 并行工作与增量（B）

- **PSALM（第 10 轮）**：本体锚定 + 对象级 SLAM 记忆，证明“对象记忆”值得做；但它的地图主要是对象槽/位姿图，不把时间偏移作为一等状态，也没有把地图查询接到 5 步伺服的执行时刻。
- **ANCHOR-ICP（第 13 轮并行候选）**：腰部运动学替代 IMU + 双目点云配准 + 桌面锚定场景图，证明“KIN-IMU + 双目几何”可行；但它的核心是米制场景图/ICP，不是目标中心的时间对齐地图，也没有用运动互相关估延迟。
- **STAF-SERVO（第 13 轮并行候选）**：固定窗口 SE(3) 因子图 + 协方差调度 + 风险感知伺服，解决“窗口内融合”；TICK-SLAM 解决“窗口外的记忆 + 时间校准 + 轻量分层”，两者可以叠加：STAF 可以做 Tier 1/2 的估计器内核，TICK-SLAM 提供时间查询和回环。
- **CHUNK-SERVO（第 12 轮）**：提供 30 步规划 + 5 步伺服骨架；TICK-SLAM 只替换它的目标估计与时间假设。

| `ρ` | Huber/鲁棒核 |
| `K_W` | 腕部 color 内参（已知） |
| `T_EW` | 腕部相机到 EE 的手眼外参（待标定/在线 refine） |
| `d_t, n_t` | 夹爪到局部表面的距离/法向（第 11 轮） |
| `r_static, r_grasp` | 静止/刚性抓持残差（第 11 轮） |
| `s_t` | 场景变化分数/编辑分数 |

### 2.2 状态与因子

Tier 1（误差状态 EKF）：

```math
\mathbf x_t=\left(T_{MH_t},\ \xi^H_t,\ T_{MT_t},\ \xi^T_t,\ \tau\right),
\qquad
P_t\in\mathbb R^{d\times d},\ d\approx 24.
```

Tier 2（固定滞后 MAP）：

```math
\mathcal X=\left\{T_{MH_k}\right\}_{k\in\mathcal K}
\cup\left\{T_{MT}\right\}
\cup\left\{\mathbf p_j^M\right\}_{j\in\mathcal L}
\cup\left\{T_{EW}\right\}.
```

因子：

```math
\begin{aligned}
r_{ij}^{\mathrm{prop}}&=\log\left((\Delta T_{ij}^{\mathrm{prop}})^{-1}T_{MH_i}^{-1}T_{MH_j}\right),\\
\Delta T_{ij}^{\mathrm{prop}}&=T_{BH}(q_i)^{-1}T_{BH}(q_j)\quad(\text{底座固定}),\\
r_{ij}^{\mathrm{stereo}}&=
\begin{bmatrix}
\pi_H(T_{HM}\mathbf p_j^M)-\mathbf u_{ij}^{L}\\
\pi_H(T_{HR}T_{HM}\mathbf p_j^M)-\mathbf u_{ij}^{R}
\end{bmatrix},\\
r_{ij}^{\mathrm{wrist}}&=
\pi_W(K_W,T_{WE}T_{EM}\mathbf p_j^M)-\mathbf u_{ij}^{W},\\
r_{ij}^{\mathrm{prior}}&=\log\left((T_{MT}^{\mathrm{demo}})^{-1}T_{MT}\right),\\
r_{kl}^{\mathrm{loop}}&=\log\left(\hat T_{kl}^{-1}T_{MH_k}^{-1}T_{MH_l}\right),\\
r_{i}^{\mathrm{rigid}}&=\log\left((T_{ET}^{c})^{-1}T_{EM_i}T_{MT_i}\right),\\
r_{i}^{\mathrm{static}}&=\log\left(T_{MT_{i-1}}^{-1}T_{MT_i}\right).
\end{aligned}
```

其中 `ρ` 用于视觉/回环/刚性因子；`r_static` 在变化点处断开（目标被移动）而不是硬压回旧地图。

MAP 目标：

```math
J(\mathcal X)=
\sum_{\mathrm{prop}}\|r^{\mathrm{prop}}\|^2_{\Sigma_p}
+\sum_{\mathrm{stereo}}\rho(\|r^{\mathrm{stereo}}\|^2_{\Sigma_s})
+\sum_{\mathrm{wrist}}\rho(\|r^{\mathrm{wrist}}\|^2_{\Sigma_w})
+\sum_{\mathrm{prior}}\|r^{\mathrm{prior}}\|^2_{\Sigma_0}
+\sum_{\mathrm{loop}}\rho(\|r^{\mathrm{loop}}\|^2_{\Sigma_l})
+\sum_{\mathrm{rigid}}\rho(\|r^{\mathrm{rigid}}\|^2_{\Sigma_c})
+\sum_{\mathrm{static}}\|r^{\mathrm{static}}\|^2_{\Sigma_t}.
```

### 2.3 时间模型

```math
t^{\mathrm{img}}=t^{\mathrm{prop}}+\tau_s,
\qquad
t^{\mathrm{obs}}_{n+1}=t^{\mathrm{send}}_n+\frac{H_c}{f_c}+\tau_a,
\qquad
\tau=\tau_s+\tau_a.
```

`τ_s` 可以为正或负；`τ_a` 是本报告相对第 12 轮新增的“端到端额外延迟”。若只能估到其中一个，另一个用保守上界，并把协方差放大；不要假设 `τ_a≈RTT`。

### 2.4 输出与评价

地图查询输出：

```math
\hat T_{MT}(t+\hat\tau)=\hat T_{MT}(t)\exp(\hat\tau\hat\xi^T_t),
\qquad
\Sigma_T(t+\hat\tau)=\Sigma_T(t)+\hat\tau^2\Sigma_{\xi^T}+Q_\tau.
```

伺服用 `T_BT=T_BM·T_MT`；评价除了成功率，还要看：目标位姿误差、NEES（协方差是否校准）、`τ` 误差、回环精度/召回、地图漂移、VLA 调用数、p99、CPU/内存。

### 2.5 可辨识性条件

地图/时间校准只在以下条件同时满足时启用：

1. 目标在头部双目或腕部视野内；目标模板有 ≥4 个非共线 3D 点；
2. 双目 ROI 有效像素 ≥70%，或腕部特征 inlier ≥15；
3. 相机标定误差在门限内（重投影 ≤5px）；
4. 目标相对位姿协方差低于阈值；
5. 时间校准的激励足够：腕部/头部 twist 超过阈值、光流 inlier ≥50%、相关峰足够尖；
6. 任务/阶段属于刚体接触类（A 档）。

任一条不满足 → 回退 Tier 1/Tier 0；不硬做回环，不硬估 `τ`。

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
                    ┌─────────────────────────────────────┐
                    │ Evaluator (N ports 8765..8765+N-1)  │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │ Per-port PolicyService (CPU)        │
                    │ ├─ CHUNK-SERVO (VLA 30 + servo 5)   │
                    │ ├─ TICK-SLAM                       │
                    │ │   ├─ KIN-IMU                     │
                    │ │   ├─ TimeCal (τ_s, τ_a)          │
                    │ │   ├─ TargetMap (keyframes/LM)    │
                    │ │   ├─ LoopClosure / ChangePoint   │
                    │ │   └─ Query(t+τ)                  │
                    │ └─ VLA gate (geometric/semantic)   │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │ Shared VLA server (GPU)             │
                    │ UnifoLM-WLA-1.0, 30-step plan       │
                    └─────────────────────────────────────┘
```

- 每个端口一个 `PolicyService`，独立 `reset()`、独立地图、独立 goal/plan cache。
- 重 BA/回环在后台线程；`get_action` 只读最新地图状态，查询 O(1)，绝不阻塞。
- 共享 VLA server 用 session ID 区分端口；模型权重只有一份，不违反单模型。
- 演示模板库/描述子库只读共享（copy-on-write），地图状态每端口独立。

### 3.2 数据流

```text
obs_t ──► KIN-IMU ──► 预测 T_MH, ξ^H
   │           │
   │           └──► TimeCal ──► τ̂, confidence
   │
   ├──► TargetMap (Tier 1 EKF / Tier 2 BA)
   │        │
   │        ├──► T̂_MT(t), Σ_T(t)
   │        └──► NIS/CUSUM ──► LoopClosure/ChangePoint
   │
   └──► VLA gate ──► (keep plan | async replan)
                         │
get_action(t) ──► Query(t+τ̂) ──► CHUNK-SERVO ──► chunk
```

### 3.3 状态机

```text
INIT ──first obs──► MAP_INIT ──target found──► TRACK
  │                    │                         │
  │                    └─target not found──► TIER0 (CHUNK-SERVO)
  │                                              │
  │                                              ├─ d_t < d_c ──► CONTACT
  │                                              │                 │
  │                                              │                 └─ release ──► TRACK
  │                                              │
  │                                              └─ NIS alarm ──► RELOCALIZE
  │                                                                   │
  │                                                                   ├─ same target moved ──► MAP_UPDATE
  │                                                                   ├─ new object ──► VLA_REPLAN
  │                                                                   └─ target lost ──► TIER0
  └───────────────────────────────────────────────────────────────────┘
任意状态 ──task success / max steps / timeout──► DONE
```

- `MAP_INIT`：用演示模板匹配 + PnP 初始化；失败就 Tier 0。
- `TRACK`：Tier 1 默认；遮挡/透明/长任务升 Tier 2。
- `CONTACT`：沿用第 11/12 轮 `d_t, n_t, r_static, r_grasp`；法向缩幅、切向保留。
- `RELOCALIZE`：停 → 目标 ROI 匹配 → PnP/变化点 → 更新或重规划。
- `TIER0`：地图不可用；CHUNK-SERVO 照常返回合法动作。

### 3.4 接口契约

- 观测：沿用 CHUNK-SERVO 的 metadata；不新增图像键；地图层只读四路 RGB + 本体。
- 动作：地图层不改变动作空间；只给 CHUNK-SERVO 提供 `T̂_MT, Σ_T, τ̂, validity`。
- 每个 `get_action` 必须返回合法 chunk；地图超时/异常 → 用上一有效状态 + 协方差膨胀 + Tier 0。
- `reset()` 清空地图/关键帧/τ/回环库；不跨 episode 复用目标位姿（模板库可复用）。

## 4. 算法

### 4.1 KIN-IMU

输入：`q_t`（`lower_body[-3:]` 腰关节）、`T_BE(t)`、可选 `pivot`。

步骤：

1. 用 URDF 正运动学算 `T_BH(q_t)`；底座固定时 `T_MH=T_MB·T_BH`。若 `pivot` 非零，把 `u_t` 积分成 `T_MB(t)`。
2. 有限差分 twist：

```math
\tilde\xi^H_t=\frac{1}{\Delta t}\log\left(T_{BH}(q_{t-1})^{-1}T_{BH}(q_t)\right),
\qquad
\tilde\xi^E_t=\frac{1}{\Delta t}\log\left(T_{BE}(t-1)^{-1}T_{BE}(t)\right).
```

3. 协方差传播：

```math
\Sigma_\xi=J_q\Sigma_qJ_q^\top/\Delta t^2+\Sigma_{\mathrm{fd}},
```

`Σ_fd` 由加速度/差分噪声给出；对 twist 做一阶低通，但保留原始值给时间校准。
4. 激励监控：`||ω||>ω_min`、`||v||>v_min`、关节速度/加速度在限内；不满足时标记 `τ` 不可观测。
5. 若 raw IMU 可用：换成标准预积分因子（旋转/速度/位置），bias 用随机游走；接口不变。

### 4.2 时间校准

#### 4.2.1 视觉信号

- 腕部：在 ROI 内用 ORB/Lucas-Kanade 跟踪静态背景特征；RANSAC 剔除目标/手臂上的动态点；得到光流 `f_t^W`。
- 头部：同样在 ROI 内跟踪背景；得到 `f_t^H`。头部自然运动小，只做辅助。
- 预测光流：由 twist、landmark 深度、相机模型算 `\hat f_t(\tau)`。

#### 4.2.2 一维搜索

```math
\hat\tau=\arg\min_{\tau\in[-100,300]\mathrm{ms}}
\sum_{t\in\mathcal T_{\mathrm{exc}}}
\rho\left(\sum_j\left\|f_{tj}-\hat f_{tj}(\tau)\right\|^2_{\Sigma_f}\right).
```

- 先把信号插值到 1kHz，搜索 1ms 网格；用抛物线拟合峰值细化。
- `\mathcal T_exc` 只选激励足够的帧；inlier <50% 或峰值不尖 → 不更新。
- 置信度：峰值高度、峰宽、inlier 比例、残差、激励幅度；低于阈值 → 保持先验并膨胀协方差。

#### 4.2.3 动作-观测延迟

用命令 EE twist 与地图/腕部观测到的 EE twist 做互相关：

```math
\hat\tau_a=\arg\max_{\tau}\sum_t
\left\langle \xi^{E,\mathrm{cmd}}_{t-\tau},\ \xi^{E,\mathrm{obs}}_t\right\rangle.
```

若腕部看不到 EE，用头部看到的臂/目标相对运动；若都不可观测，`τ_a` 用保守上界（如 150ms），并关掉高增益预测。

#### 4.2.4 更新与回退

```math
\tau_{k+1}=\tau_k+K_\tau(\hat\tau-\tau_k),
\qquad
\sigma_{\tau,k+1}^2=(1-K_\tau)\sigma_{\tau,k}^2+Q_\tau.
```

- `K_τ` 按置信度调度；置信度低时 `K_τ→0`。
- 不估计时，用 `τ_prior`（如 100ms）+ 大协方差；伺服只做低增益位置修正，不做高速预测。
- 可选“tick scan”：episode 开始若手臂静止，做 0.3–0.5s 小幅度腰部 yaw 正弦（±0.03rad），给头部时间校准和地图视差；必须在安全限内、回原位。若评测不允许，跳过，等自然 reach。

### 4.3 目标模板与地图初始化

#### 4.3.1 离线模板

对每个任务：

1. 选 20–50 条成功演示；用 `state_torso/state_d435`（或腰 FK）恢复头部相机位姿。
2. 在接触前关键帧上，用头部双目 + 已知相机位姿三角化目标/受器上的 20–40 个稀疏点。
3. 用成功抓取帧的 `T_ET*` 定义目标系 `T`（或按任务几何定义：杯钩中心、网口平面、锁孔轴、碗沿圆）。
4. 存 `{(p_j^T, descriptor_j)}`、关键帧 ROI、任务/相位标签；验证留出演示的重投影 ≤3px、位姿一致性 ≤5mm/2°。

模板是**确定性几何资产**，不是第二个模型；它来自官方 33k 演示，不引入外部数据。

#### 4.3.2 在线初始化

1. 用语言/任务 ID 选模板；在当前头部图/腕部图 ROI 做 ORB/描述子匹配。
2. PnP + RANSAC 初始化 `T_MT`；用头部双目做尺度校验；用桌面平面约束 roll/pitch。
3. 置信度低（inlier <15、重投影 >5px、深度不一致）→ 不初始化，Tier 0。
4. 初始化成功后建第一个关键帧；目标 landmarks 进入地图。

### 4.4 跟踪与固定滞后 BA

#### 4.4.1 Tier 1 EKF

- 状态：`T_MH, ξ^H, T_MT, ξ^T, τ`；误差状态在 SE(3) 切空间。
- 预测：KIN-IMU 传播 `T_MH`；目标用恒速模型 `T_MT←T_MT exp(ξ^T Δt)`；`τ` 用随机游走。
- 更新：PnP/双目/腕部测量；NIS 门控；鲁棒核。
- 协方差：`P←(I-KH)P`；过程噪声 `Q` 按激励/图像质量调度。
- 输出 `T̂_MT, Σ_T`；Tier 1 不建长期回环，只做短窗跟踪。

#### 4.4.2 Tier 2 固定滞后 BA

- 关键帧选择：平移 >1cm、旋转 >2°、目标 ROI 重叠 <60%、或距上一关键帧 >0.5s。
- 窗口 `K=5–8`；landmarks 30–50；固定滞后，旧关键帧边缘化；目标 landmarks 保留。
- 因子：prop + stereo + wrist + target prior + loop + rigid + static；Huber。
- 求解：Gauss-Newton/Levenberg-Marquardt，3–5 次迭代；稀疏 Schur complement；数值失败 → 回 Tier 1。
- 动态点处理：RANSAC/光流一致性剔除人手/运动物体；目标被移动时断开 `static` 因子。

### 4.5 回环与变化点

#### 4.5.1 回环

- 目标被遮挡后重新出现，或关键帧间隔 >1s：用目标 ROI 描述子（ORB/BoW/颜色直方图）检索旧关键帧。
- 对 top-k 候选做 PnP/模板匹配；inlier ≥15、重投影 ≤3px、时序一致（连续 2 帧）才接受。
- 加回环因子 `r_loop`；更新 `T_MT` 与协方差；回环只修正地图，不直接改 VLA 计划。

#### 4.5.2 变化点

NIS：

```math
d_t^2=\nu_t^\top S_t^{-1}\nu_t,
\qquad
S_t=H_tP_tH_t^\top+R_t.
```

CUSUM：

```math
g_t=\max\left(0,\ g_{t-1}+\frac{d_t^2-m}{\sqrt{2m}}-\nu\right),
\qquad
\text{alarm if }g_t>h.
```

报警后：

1. **假设 A：遮挡/外点** → 膨胀协方差，跳过更新，继续跟踪。
2. **假设 B：同一目标被移动** → 重新匹配目标 ROI，PnP 估计新位姿；若连续 2 帧一致、inlier 足够，建立新目标节点/变化点，重置 `static` 因子；旧节点保留为历史。
3. **假设 C：目标被拿走/换成新物体** → 目标丢失 >`T_lost` 或外观/几何匹配失败；请求 VLA 重规划；地图进入 `TIER0`。

变化点检测的误报率是第一道门（G12）：宁可多停一次，不可把“移动后的目标”硬接回旧地图。

### 4.6 查询与伺服

查询：

```math
\hat T_{MT}(t+\hat\tau)=\hat T_{MT}(t)\exp(\hat\tau\hat\xi^T),
\qquad
T_{BT}=T_{BM}\hat T_{MT}(t+\hat\tau).
```

期望 EE：

```math
T_{BE}^{d}=T_{BT}T_{TE}^{*},
\qquad
e=\log\left(T_{BE}^{-1}T_{BE}^{d}\right).
```

增益：

```math
K_{\mathrm{eff}}=
K_0\cdot
\frac{\sigma_0^2}{\sigma_0^2+\lambda_{\max}(\Sigma_T)}
\cdot
\frac{1}{1+\hat\tau/\tau_0},
\qquad
K_{\mathrm{eff}}\in[K_{\min},K_0].
```

修正：

```math
\Delta=\operatorname{clip}\left(K_{\mathrm{eff}}e+D\dot e,\ \pm\delta_p,\pm\delta_r\right),
\qquad
T_{BE}^{\mathrm{cmd}}=T_{BE}^{d}\exp(\Delta).
```

- 目标静态时 `ξ^T≈0`，预测主要补偿 EE/相机运动；目标被人移动时 `ξ^T` 由 Tier 1 估计，但增益按 `Σ_T` 降档。
- `Σ_T` 大或 `τ̂` 置信度低 → `K_eff→0`，回退到第 12 轮的低增益/开环。
- 接触段沿用第 11 轮法向/切向分解；滑移/编辑报警 → 停/重定位/重规划。

### 4.7 VLA 门控

定义：

```math
\text{semantic change}=
\mathbb 1[\text{target identity changed}]
\lor\mathbb 1[\text{target lost}>T_{\mathrm{lost}}]
\lor\mathbb 1[\text{phase transition}],
```

```math
\text{geometric change}=
\left\|\hat T_{MT}(t)-T_{MT}^{\mathrm{plan}}\right\|_{\Sigma}.
```

规则：

- `geometric change` 高、`semantic change` 低：目标还是同一个，只是位置变了；更新地图，**不重规划**，伺服重新瞄准。
- `semantic change` 高：异步请求 VLA 重规划；请求期间继续用旧 plan + 伺服，绝不阻塞 `get_action`。
- 计划 TTL 上限：即使没有语义变化，`plan_age > T_max` 也重规划，防止语义漂移。
- 目标：稳定场景 VLA 调用 ↓≥30%，成功率不回归（G11）。

### 4.8 Anytime 分层

| Tier | 内容 | 触发 | 预算 | 回退 |
|---|---|---|---|---|
| 0 | CHUNK-SERVO，无地图 | 地图初始化失败/超时/异常 | <5ms | — |
| 1 | EKF 目标跟踪 + 时间校准 | 默认 A 档；地图已初始化 | <2ms/帧 | Tier 0 |
| 2 | 固定滞后 BA + 回环/变化点 | 遮挡/透明/长任务/人扰；Tier 1 NIS 高 | 5–10ms 均值，<20ms p99 | Tier 1 |

调度：

- 后台线程跑 Tier 2；`get_action` 只读最新结果；结果过期 >100ms → 用 Tier 1/0。
- CPU 预算：每端口 10ms/帧均值；连续 3 帧超 20ms → 降级；连续 10 帧低于 5ms 且 NIS 高 → 升级。
- 迟滞：升级/降级各有不同阈值，避免抖动。

### 4.9 伪代码

```python
class TickSlam:
    def __init__(...):
        self.tier = 1
        self.kin = KinImu(urdf, waist_map)
        self.timecal = TimeCal()
        self.map = TargetMap(templates)
        self.change = ChangeDetector()
        self.last_valid = None

    def on_obs(self, obs):
        q = obs.lower_body[-3:]
        self.kin.update(q, obs.ee_pose)
        self.timecal.update(obs.images, self.kin.twists, self.kin.excitation)

        if not self.map.initialized:
            if not self.map.init_from_template(obs):
                self.tier = 0
                return

        if self.tier == 1:
            self.map.ekf_predict(self.kin, self.timecal.tau)
            self.map.ekf_update(obs)
        elif self.tier == 2:
            self.map.add_measurements(obs)
            if self.map.need_keyframe():
                self.map.add_keyframe(obs)
                self.map.schedule_background_ba()

        alarm = self.change.update(self.map.nis)
        if alarm:
            self.relocalize_or_replan(obs)

    def query(self, t_exec):
        if self.tier == 0 or self.map is None:
            return None
        tau = self.timecal.tau
        T, Sigma = self.map.predict(t_exec + tau)
        if not self.map.valid(T, Sigma):
            return None
        return T, Sigma, tau

    def get_action(self, obs):
        self.on_obs(obs)
        goal = self.query(obs.timestamp_estimate)
        if goal is None:
            return self.chunk_servo(obs, use_map=False)
        return self.chunk_servo(obs, goal=goal, use_map=True)
```

注意：`obs.timestamp_estimate` 不是 API 时间戳，而是策略内部维护的“当前观测的等效时刻”；如果 API 无 timestamp，就用收到观测的本地时间 + `τ` 估计。具体实现必须避免把网络抖动误当成世界运动。

## 5. 复杂度

### 5.1 计算

| 组件 | 复杂度 | 典型预算 |
|---|---|---:|
| KIN-IMU（FK + 差分） | O(1) | <0.1ms |
| 时间校准（1D 搜索 + 光流） | O(T·L + T·Δτ^{-1}) | 0.2–1ms |
| Tier 1 EKF | O(d^3+Md^2)，d≈24 | <0.5ms |
| Tier 2 BA | 稀疏 O((6K+3L)^3)（实际远低） | 5–10ms |
| 回环检索 | O(N_desc) + PnP | 1–3ms |
| 查询 | O(1) | <0.1ms |

`K=5–8, L=30–50` 时，Tier 2 变量约 126–204 个；稀疏 Cholesky + Schur complement 在单 CPU 核上 5–10ms 可行。特征提取是大头：ROI 限制在 128×128/240×320，ORB 100–200 点，约 2–4ms。

### 5.2 内存与通信

- 关键帧：5–8 ×（位姿 6 + 协方差 21 + ROI 缩略图/描述子）≈ 几 MB。
- Landmarks：30–50 ×（3D + 描述子）≈ 几 MB。
- 模板库：32 任务 × 20–40 点 × 描述子 ≈ 几十 MB；共享只读。
- 总每端口 <200MB；不存原始视频，只存 ROI 缩略图/描述子。
- 通信：不新增图像键；地图在 PolicyService 本地算，不占 GPU/上行带宽。

### 5.3 最坏情况

- Tier 2 BA 超时/数值失败 → 立即回 Tier 1；保留上一有效位姿 + 协方差膨胀。
- 回环误匹配 → inlier/重投影/时序三重门拒绝；不更新地图。
- `τ` 不可观测 → 用先验 + 大协方差；关预测，只做低增益位置修正。
- 目标丢失 → Tier 0；CHUNK-SERVO 继续返回合法动作。

## 6. 正确性

> 以下“正确性”指估计器/控制器的性质，不是任务成功率承诺。任务成功率必须由 G8–G12 实测。

### 6.1 目标位姿可观测性

**命题 1**：若目标模板有 ≥4 个非共线 3D 点，且至少一个标定相机观测到它们，则 `T_MT` 在局部可观测；双目/多视图提供尺度与深度约束。共面点存在平面二义性，用多视图/桌面先验消除。

**证明要点**：PnP 的投影雅可比对 6DoF 满秩（非共线）；双目重投影增加尺度约束；多视图的 Fisher 信息叠加，协方差不增。腕部单目 + 已知模板也能给 6D（模板给尺度），但模板误差会直接进位姿误差；头双目做独立尺度校验。

### 6.2 时间偏移可观测性

**命题 2**：若视觉光流与本体 twist 由同一相机运动产生，且激励矩阵

```math
\mathcal I(\tau)=\sum_t
\left(\frac{\partial \hat f_t(\tau)}{\partial \tau}\right)^\top
\Sigma_f^{-1}
\left(\frac{\partial \hat f_t(\tau)}{\partial \tau}\right)
```

正定，则 `τ` 在局部可辨识；若运动周期化，互相关有多峰，需要宽带激励/先验。

**证明要点**：一维最小二乘在 `I(τ)>0` 时局部强凸；周期信号的自相关多峰导致全局歧义。数据探针 P1 说明腰部自然运动激励弱、腕部 reach 激励强；P2 说明 1kHz 插值下数值可到 1ms。

### 6.3 地图一致性与回环

**命题 3**：在高斯噪声、正确数据关联下，固定滞后平滑是 MAP 估计；线性高斯情形下，增加回环因子不会增大目标边缘协方差（Schur complement 的 PSD 性质）。鲁棒核/门控把外点剔除；若目标被移动，静态模型被违反，必须由变化点检测处理，否则估计有偏。

**证明要点**：MAP 目标的海森是信息矩阵；增加观测项使信息矩阵 PSD 增加；边缘协方差是信息矩阵逆的子块，故不增。变化点不是“更多约束”，而是“模型切换”；不能靠回环硬接。

### 6.4 变化点检测

**命题 4**（标准 CUSUM 性质）：在 H0（无变化）下，CUSUM 的误报率随阈值 `h` 指数下降；在 H1 下，检测延迟与 `h/漂移` 成正比。我们不需要证明新定理，只需用标准结果选 `h` 并按任务校准。

**实践**：`m` 取 NIS 的均值（自由度），`ν` 取容忍漂移；`h` 用离线正常数据的分位数校准，要求误报 ≤5%、检测 ≤200ms（G12）。

### 6.5 有界修正

**命题 5**：伺服修正被 `δ_p,δ_r` 截断，增益 `K_eff` 随 `Σ_T` 和 `τ` 单调不增；因此命令位姿始终在 VLA 前馈的有界邻域内。若 `Σ_T→∞` 或 `τ` 不可信，`K_eff→K_min`（或 0），系统退化为 CHUNK-SERVO/开环。

**证明要点**：`clip` 直接给出范数上界；`K_eff` 的公式对 `λ_max(Σ_T)` 和 `τ` 单调；组合即得有界性。这是安全性质，不是精度性质。

### 6.6 延迟预测误差界

**命题 6**：若目标/EE 运动是 `L`-Lipschitz，速度估计误差为 `ε_v`，则

```math
\left\|e(t+\tau)-\hat e\right\|
\le L|\tau-\hat\tau|+\tau\varepsilon_v.
```

**证明要点**：三角不等式 + Lipschitz 定义。含义：`τ` 估得越准，预测误差越小；`τ` 估错时误差线性增长。这直接支撑 G9 的必要性。

### 6.7 局限

- 目标刚性静止是分段假设；人手在遮挡窗口内移动目标会触发变化点，但检测有延迟。
- 透明/反光/变形目标的模板/特征不可靠；Tier 2 不保证。
- 手眼外参/相机标定误差会进地图；G0 必须先过。
- 时间校准在低激励时不可观测；G9 必须先过。
- 以上性质都是局部/渐近的；不替代真机 A/B。

### 7.6 统计

- 总分 `S=(1/32)Σp_t`；320 trials 下 `p≈0.25` 的 SE≈2.42pp。
- 配对 A/B 的差值方差取决于任务内相关；报告配对差值的 bootstrap 95% CI，不只报两个平均值。
- 5 次/任务只能看方向，不能看显著性；不要用 +1–2pp 做结论。
- 人扰轴 = 2/10 = 20%；若 human 轴 +10pp，全局 +2pp。
- A 档 8–10 任务各 +5–10pp → 全局 +1.5–3pp；叠加 human +1–2pp；保守合计 +2.5–5pp。**这是设计目标，不是承诺。**

## 9. 风险与合规

### 9.1 单模型合规

TICK-SLAM 是**确定性估计器/控制器**：KIN-IMU 是 URDF/关节运动学，地图是稀疏几何 + ORB/光流 + PnP/BA，回环是描述子匹配，没有学习权重；VLA 仍是唯一学习模型。对应第 12 轮的 C2 模式。若组委会把“任何外部几何模块”都算模型，退到 C1（只离线用地图生成标签，线上只用 VLA）或提交书面说明。禁止：加载第二个学习策略/残差网络/独立学习视觉编码器做在线决策。

### 9.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 目标刚性静止假设 | 人移动目标后回环接错，自信追错 | 变化点 + 几何/外观双重验证；不确定就停/回退 |
| 无 raw IMU/timestamp | 时间校准退化 | 腕部自然运动激励强；机会式更新 + 保守先验；G9 门控 |
| 腕部手眼缺失 | PnP/伺服偏差 | 一次性棋盘格 + 在线 refine；头双目独立校验 |
| 透明/反光/变形 | 特征/深度失效 | 只对刚体任务启用 Tier 2；ROI/边缘/腕部近距；回退 |
| 回环误匹配 | 地图污染 | inlier/重投影/时序三重门；误匹配不更新 |
| 计算超预算 | p99 上升 | 异步 + anytime + 事件触发；G10 硬门 |
| VLA 计划与地图冲突 | 伺服和规划打架 | 几何变化归伺服，语义变化归 VLA；限幅 + 仲裁 |
| 单模型解释 | 被判第二个模型 | 确定性几何/控制，无学习权重；C2 合规说明 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组；相邻帧不跨 split |
| 目标移动检测延迟 | 追旧目标 200ms | CUSUM 持续报警 + 停止策略；安全优先 |

### 9.3 安全

- 修正限幅：每块最多 1cm/0.05rad；接触段法向缩幅。
- 变化点报警：先停，再重定位；不确定不继续追。
- 地图失效/超时：Tier 0，CHUNK-SERVO 返回合法动作。
- 最大重试次数/超时；任何异常返回上一合法 chunk 或安全 hold。
- 不假设人扰 100% 可检测；不声称。

## 12. 一句话押注与最大风险

**一句话押注**：把 CHUNK-SERVO 的“每 167ms 看一次”升级为“每 167ms 看一次，而且知道这张图的时间、目标的历史、下一次执行时目标的位置”；用 KIN-IMU 估延迟，用目标中心局部 SLAM 记住遮挡，用 anytime 分层守住 CPU。

**最大风险**：TICK-SLAM 把“目标在两次观测之间刚性静止”写进了地图先验；一旦人手在遮挡窗口内移动目标，回环可能把新位姿错误地接回旧地图，系统会比开环更自信地追错目标。所以本轮的第一道门不是地图精度，而是**变化点检测的误报率**。
