# 第 59 轮（承接第 58 轮「KGMM×SFT-KG×UXSE×KGES×ACC×PCX++」IP-139~144；本轮灵感：「并发推理」×「续航能力」）

> 第 58 轮把安全论证从"证据承诺"推进到"结构化记忆守护下的安全自适应"：知识图谱同时驱动元推断、OOD、微调、证据合成与心智预测，并以隔离写入、边级溯源、事后证伪回溯防止"图里写着的知识"绕过证据门。但它仍然隐含了两个"实验室假设"：**(a) 推理是串行且时间近乎无限**——探询调度、共形监测、KG 更新、影子微调、UX 估计、证据门被默认可按任意顺序、任意时长执行，共享状态没有并发语义；一旦真正并发，读-改-写竞争、陈旧读、乱序提交会让"更保守"的单调性失效，甚至让旧快照解锁新承诺。**(b) 能量是软指标**——第 58 轮只有探针/微调/解释三类计数预算，没有焦耳，没有安全返航储备，也没有把"推理本身耗能"计入证据成本；低电量不是风险状态，而只是"跑得慢一点"。本轮两个灵感各补一条腿：**并发推理**把共享安全状态变成可线性化、可快照、可合并的证据账本，让并发只能收紧不能放松；**续航能力**把能量提升为与证据同级的硬约束，给出安全返航储备、续航证书与随能量连续收缩的能力包络。核心命题由"结构化记忆守护的安全自适应"升级为 **"并发可线性化、能耗可预算、降级可证明的实时证据承诺"**。

核心矛盾：
- **H33（并发 vs 单调）**：第 57/58 轮的单调性证明全部默认顺序执行；并发读-改-写可以把"收窄"排到"证据追加"之前，让一个本该更保守的状态被更自信的旧快照覆盖——安全上最危险的不是算得慢，而是**旧快照解锁了新承诺**。
- **H34（续航 vs 证据）**：采集证据要耗能；更多证据在认识论上更安全，却可能让机器人回不到安全态。最"该信"的动作可能正是最"付不起"的动作，证据门与能量门会互相否决。
- **H35（推测 vs 浪费）**：并发推测买延迟，但失败分支的能耗是沉没成本，而且可能正好花掉了返航储备；推测越激进，续航越短，返航风险越高。
- **H36（实时 vs 完备）**：截止期逼着系统在证据不完整时决策；"迟到但完整"的提交在实时系统里等同于失败，正确方向是"按时但保守"。

## 0. 直觉与动机

**灵感 1（并发推理 → 可线性化的证据账本）**
直觉：把安全状态想成一本多人同时记账的账本。第 58 轮的所有单调性证明都默认"一个人按顺序记账"；一旦多个推理线程同时读-改-写，就可能出现：共形监测线程用旧残差把带收窄，而证伪线程刚把该残差标脏；微调线程热切换了校准层，而证据门还在读旧版本；KG 的证伪删除与新增边交错，导致"删掉的欺骗边又活了"。安全上真正危险的不是"算得慢"，而是**旧快照解锁了新承诺**。所以并发设计的第一原则是：**会放松安全的操作必须单写者定序并回读校验；只会收紧的操作才可以无锁合并**。信念加宽、证据追加、KG 删除、授权降级是可交换的单调操作（join-semilattice）；收窄、授权升级、证据类解锁、超时缩短是非单调操作，必须经过一个线性化点（提交定序器）并在读集版本变化时中止重算。

**灵感 2（并发推理 → 推测探询与验证后提交）**
直觉：并发不只是"多线程跑同一件事"，更是"同时押注多个假设"。机器人可以用两个模态同时探、同时展开两条绕行方案、同时跑"这是冰"与"这是水"两个解释，谁先被验证谁提交。推测买到的是延迟，付出的是能量：失败分支的能耗是沉没成本，而且可能正好花掉了返航储备。因此推测必须**先隔离、后验证、再提交**，只能花"机会预算"，永远不能动"安全储备"；并发佐证还必须**血缘不相交**，否则两个分支共享同一份证据却被当成两次独立确认，就是把同一个错误问了两遍。

**灵感 3（续航能力 → 能量门与续航证书）**
直觉：能量不是"还能跑多久"的仪表盘，而是**安全的前提条件**。一个"再探一次就能确认"的动作，如果探完回不到安全态，它在安全上就是不可接受的。把能量想成第二道门：证据门回答"我该不该信"，能量门回答"我付不付得起"。任何不可逆承诺必须同时过两道门；能量门不是证据类，不能拿来替代证据，只能否决。规划期还要有**续航证书** H_endur(δ)：以 ≥1−δ 的概率，未来 H 内电量始终高于安全返航储备——这才是"续航"的形式化，而不是电量百分比。

**灵感 4（续航能力 → 能力包络与有不变式的降级）**
直觉：低电量不该是"突然关机"，而应是**能力连续收缩**：满电时能跳 20cm、能开 8 路推测；20% 时只能慢走、只保留安全关键线程、解释超时更长、探针更少。能力包络 ρ_S(d; b, θ) 随电量 b 单调增、随温度 θ 单调减；动作可行性不是二值，而是随 b 收缩的集合。再配一条有不变式的降级阶梯：正常 → 节能（降并发/降探针率）→ 最小（只留安全关键）→ 返航 → 停/人接；降级实时，升级要攒恢复证据与驻留时间，且热降额/电量抖动不能来回抖振。

**灵感 5（合流 → 安全关键并发调度、七类证据门、双门提交）**
直觉：并发必须服从优先级——提交定序器、安全监测、能量门是 C0 安全关键线程，必须有预留算力与预留能量、wait-free 可读；推测、影子微调、UX 渲染是 C2 机会线程，可抢占、可饿死。截止期到了但证据不完整，正确做法不是"迟到地完整提交"，而是"按时地保守放弃"——**迟到即保守**。于是第 58 轮六类证据门加一个 **EV-conc**（并发独立佐证，限 L1），并与**能量门**组成双门；击穿安全需要：并发定序失效 ∧ 陈旧读解锁 ∧ 推测验证漏检 ∧ 能量模型乐观 ∧ 储备误算 ∧ 调度饿死安全线程 ∧ 人也错——纵深从五层扩到八层。

## 1. 形式化定义（增量：定义 145–150）

**定义 145（并发证据账本 CEL）** 安全状态 σ=(𝓑,𝒢,{q_v},s_o,e)，事件 e=(tid,op,read_set,write_set,payload,ver)。单调算子 ⊔ 对信念（加宽/证据追加）、KG（边新增/证伪删除，删除优先）、残差集、授权降级满足交换/结合/幂等，构成 join-semilattice；非单调算子 Op_nm={收窄,授权升级,证据类解锁,τ_int 缩短} 必须经提交定序器 SQ 单写者定序。历史 H 线性化 ⇔ ∃全序 ≤_L 与实时序一致且每个操作结果等于按 ≤_L 顺序执行规范状态机。门判定必须读已验证快照 snap(v)；若读后版本推进且 Δ 相关，则按保守者合并重判（陈旧读不得解锁）。定义并发权限单调性：A_eff(H) ⊆ A_serial(≤_L) 对任意交错成立。

**定义 146（推测探询并发 SPC）** 推测树分支 b=(h_b,P_b,d_b,c_b,V_b,ℓ_b)，h_b 假设、P_b 探针集、d_b 截止、c_b 能耗、V_b 验证谓词（独立复现/跨模态一致/共形包含）、ℓ_b 证据血缘。提交 ⇔ V_b ∧ CEL 线性化 ∧ 能量门 ∧ 证据门。并发度 k_spec=argmax_{k≤k_max}[P(d≤d_b|k)·(VOI_元悲观−λ_E·c_b(k))] 且 c_spec≤B_opp（机会预算）。血缘不相交：ℓ_b∩ℓ_b'=∅ 才可计为独立佐证；EV-conc ⇔ 两支独立 ∧ 均通过 V ∧ 与融合同侧 ∧ D(r)≤θ_D，仅限 L1，不得进入不可逆必要集。

**定义 147（能量-安全联合门 EAG）** 能量状态 e(t)，功率模型 P(s,a,κ,θ)，能耗上界 ĉ(a,κ)；安全返航储备 E_res(x)=min_{s∈S_safe}[worst-case 到达能耗 + margin(θ,payload)]。可行动作集 A_E(x)={a: e−ĉ(a,κ)≥E_res(x')}。能量门 G_E ⇔ e−ĉ(a,κ)−E_res(x')≥0。不可逆承诺 ⇔ G_ev ∧ G_E。续航证书 H_endur(δ)=max{H: P(e(t)≥E_res(t),∀t≤H)≥1−δ}；规划须满足 H_plan≤H_endur(δ)。能量账本不得透支：机会消耗 B_opp 与储备 E_res 分账，禁止借储备。

**定义 148（续航-鲁棒治理 ERG）** 能力包络 ρ_S(d;b,θ)∈[0,1] 对 b 单调不减、对 θ 单调不增；动作可行 ⇔ d≤ρ_S(d;b,θ)·d_max。降级阶梯 ℓ∈{0 正常,1 节能,2 最小,3 返航,4 停/人接}，每级 I_ℓ=(C_ℓ,k_max^ℓ,A_ℓ,Inv_ℓ,Cert_ℓ)。降级实时（e<e_ℓ ∨ θ>θ_ℓ ∨ 能量门失败）；升级需 n_recover≥N_up(ℓ) ∧ 驻留≥T_dwell ∧ 储备证书 ∧ 无污染通道。∀ℓ，Inv_ℓ 不得引用被污染/被降额通道；阶间加滞回，禁止抖振。

**定义 149（安全关键并发调度 PRS）** 线程类 C0（提交定序器/安全监测/能量门，预留算力 ρ0 与预留能量 E_C0，wait-free 读快照）/C1（探询/共形，用松弛算力）/C2（推测/影子微调/UX，可抢占）。调度须保证 C0 在声明负载下恒可调度、C1 有界饥饿自由、C2 不挤占 E_C0。截止策略：若在 d 前无法完成已验证提交，则**不得迟到提交**，改走保守动作（停/绕行/降档）；共享账本用不可变快照或优先级继承避免优先级反转。

**定义 150（探-诺-演++++ PCX++++）** 每检查点：①读已验证快照；②按 k_spec 并发展开推测分支（带血缘）；③单调分量 ⊔ 合并、非单调分量经 SQ；④在一致快照上判双门 G_ev∧G_E；⑤查降级阶与截止；⑥仅当双门过 ∧ 线性化 ∧ 未过期才提交，否则按时保守回退（绕行→降档→返航→L2/安全停）。七类证据门=EV-probe*/EV-visit/EV-margin/EV-xmodal/EV-human/EV-ft/EV-ux+EV-conc；能量门为独立否决门。

```python
def concurrent_commit(M, cp, branches, d_cp):
    snap = M.ledger.snapshot()                     # 已验证快照 snap(v)
    results = parallel_run(branches, k=M.k_spec, deadline=d_cp,
                           budget=M.B_opp)          # C2 机会预算
    for b in results:                               # 先验证后合并
        if not verify(b.V, b, snap): continue
        if b.monotone: M.ledger.join(b.payload)     # ⊔ 可交换合并
        else: M.ledger.enqueue_nm(b)                # 进 SQ 定序
    M = M.ledger.apply_sequencer()                  # 非单调单写者定序
    if M.ledger.version() != snap.version and M.ledger.relevant_delta(snap):
        snap = stale_read_merge(snap, M.ledger.snapshot())  # 保守者重判
    G_ev = evidence_gate_ppp(snap, cp)              # 七类证据门
    G_E  = M.eag.gate(M.e, cp.action, M.k_spec, M.theta, cp.x_next)
    if deadline_ok(d_cp) and G_ev and G_E and M.ledger.linearizable():
        return commit(cp.action, snap)              # 双门 + 线性化才提交
    return conservative_fallback(cp, M)             # 迟到/未过门 ⇒ 保守
```

## 3. 复杂度与正确性（要点）

| 组件 | 时间 | 空间 | 正确性关键 |
|---|---|---|---|
| CEL | 单调合并 O(\|Δσ\|)；定序 O(log N) | O(\|log\|+\|σ\|) | 单调 join 可交换、非单调单写者、陈旧读保守合并 |
| SPC | O(k_spec·(C_probe+d_verify)) | O(k_spec·\|b\|) | 验证后提交、血缘不相交、只花 B_opp |
| EAG | O(\|S_safe\|) 储备；O(1) 门 | O(1)+功率表 | 能耗上界、储备下界、双门原子 |
| ERG | O(1)/步 + O(H) 证书网格 | O(1)+阶梯表 | 包络单调、阶梯不变式、升级有据有界 |
| PRS | O(log n) 调度；快照读 O(1) | O(n_threads) | C0 预留 wait-free、迟到即保守、无优先级反转 |
| PCX++++ | O(\|CP\|·(k_spec·C_branch+C_VOI+d_GNN)) | O(\|V\|+\|σ\|+\|𝒢\|) | 一致快照、双门、有界轮次、四态完备 |

**正确性定理（并发-能量健全性 CES 概要）**：在 A33–A45 上加 (A46) CEL 单调分量构成 join-semilattice、非单调经 SQ、门读已验证快照且陈旧读不解锁；(A47) SPC 验证后提交、EV-conc 血缘不相交且限 L1、推测只花 B_opp；(A48) EAG 能耗上界与储备下界诚实、能量门与提交原子；(A49) ERG 包络单调、阶梯不变式、升级有据有界；(A50) PRS C0 预留且 wait-free、迟到即保守；(A51) PCX++++ 一致快照 + 双门 + 有界轮次。则：

(i) **线性化安全**：任意交错下的提交等价于某个串行执行，第 58 轮失效界增加 δ_conc（中止/重判）+δ_spec（推测验证漏检）；
(ii) **并发单调性**：交错只能收缩有效权限集 A_eff，除非发生已验证的 SQ 非单调提交——并发本身永不成为新的信任来源；
(iii) **能量安全**：若 e(0)≥E_res(0) 且所有动作∈A_E，则 P(∀t≤H:e(t)≥E_res(t))≥1−δ_E−δ_th，且 H≤H_endur(δ)；
(iv) **截止与终止**：C0 恒可调度、C1 有界饥饿自由、迟到必保守，PCX++++ 在 k_spec+k_probe+k_cons 内有界终止；
(v) **部署界**：把 δ_conc、δ_spec、δ_E、δ_deadline 加入第 58 轮联合界，并显式扣除 C0 饿死、能耗模型乐观、储备误算、热降额未建模四项结构风险。

## 6. 本轮最大风险

**一句话**：本轮把"并发"和"能量"同时提升为安全论证的前提，最危险的不是单独一项失效，而是二者**复合**——一个乐观的能量模型（漏算热降额/老化/负载）会让推测并发把返航储备花在失败分支上，而一个逃出定序器的非单调更新（陈旧读收窄共形带或升级授权）又会在能量门还来得及否决之前把承诺提交出去；必须以保守能耗上界、硬储备分账、单写者定序、C0 wait-free、迟到即保守五重护栏，宁可少并发、早返航、按时保守放弃，绝不接受"既快又自信、同时没电"。

```python
class ConcurrentEvidenceLedger:
    def __init__(self):
        self.state = SafetyState()          # beliefs/KG/quantiles/trust/energy
        self.version = 0
        self.log = []                       # append-only；线性化序的证据
        self.sq = CommitSequencer()         # 非单调单写者

    def snapshot(self):
        return Snapshot(copy_immutable(self.state), self.version)

    def join(self, payload):
        # 单调分量：加宽/证据追加/删除优先/降级——可无锁合并
        self.state = join_semilattice(self.state, payload)
        self.version += 1
        self.log.append((self.version, 'monotone', payload))

    def enqueue_nm(self, op):
        return self.sq.submit(op)           # 非单调操作必须定序

    def apply_sequencer(self):
        for op in self.sq.drain():
            # OCC：读集版本变了就中止重算，绝不把旧读写回新状态
            if op.read_version != self.version_of(op.read_set):
                op.abort(); self.log.append((self.version, 'abort', op)); continue
            self.state = apply_nonmonotone(self.state, op)
            self.version += 1
            self.log.append((self.version, 'nm', op))
        return self

    def relevant_delta(self, snap):
        return touches_gate_fields(self.log, snap.version, self.version)

    def linearizable(self):
        return self.sq.is_total_order() and no_lost_update(self.log)
```

```python
class EnergySafetyGate:
    def __init__(self, power_model, margin_fn):
        self.pm = power_model
        self.margin = margin_fn

    def cost_upper(self, action, k, theta):
        # 能耗上界：推理并发度 k 与热降额 theta 都进入功率模型
        return self.pm.power_upper(action, k, theta) * action.duration

    def reserve(self, x, worst_detour):
        # 最坏绕行下到达任一安全态的最小能耗 + 裕度
        return min(self.pm.energy_to_safe(s, worst_detour)
                   for s in SAFE_STATES) + self.margin(x)

    def gate(self, e, action, k, theta, x_next):
        c = self.cost_upper(action, k, theta)
        return e - c >= self.reserve(x_next, WORST_DETOUR)

    def endurance_cert(self, e, delta, horizon_grid):
        # 保守功率上界下的前向概率界：max H s.t. P(min_t e(t) >= E_res(t)) >= 1-delta
        return max(H for H in horizon_grid
                   if prob_above_reserve(e, H, self.pm) >= 1 - delta)
```

```python
class EnduranceRobustGovernor:
    # (名称, 可用通道, k_max, 动作包络, 不变式, 证书条件)
    RUNGS = [
        ('normal',  ALL_CHANNELS, K_MAX,  A_NORMAL,  INV_NORMAL,  CERT_NORMAL),
        ('conserve', SAFE_CHANNELS, K_CONS, A_CONSERVE, INV_CONSERVE, CERT_CONSERVE),
        ('minimal', C0_CHANNELS, 1,      A_MINIMAL, INV_MINIMAL, CERT_MINIMAL),
        ('return',  NAV_CHANNELS, 1,     A_RETURN,  INV_RETURN,  CERT_RETURN),
        ('handoff', NONE, 0,             A_STOP,    INV_STOP,    CERT_STOP),
    ]

    def envelope(self, b, theta):
        return clamp(monotone_inc_b(b) * monotone_dec_theta(theta), 0.0, 1.0)

    def k_max(self, rung):
        return self.RUNGS[rung][2]

    def step(self, rung, e, theta, ledger, reserve):
        # 降级实时：电量/温度/能量账本任一越线
        if rung < 3 and (e < E_TH[rung] or theta > TH_TH[rung]
                         or ledger.exhausted()):
            return min(rung + 1, 4)
        if rung == 3 and e <= E_RETURN_DONE:
            return 4
        # 升级有据有界：恢复证据 + 驻留 + 储备证书 + 无污染通道
        if rung > 0 and self.can_upgrade(rung, e, theta, ledger, reserve):
            return rung - 1
        return rung

    def can_upgrade(self, rung, e, theta, ledger, reserve):
        return (e >= E_UP[rung - 1] and theta <= TH_UP[rung - 1]
                and ledger.recovered_for(rung) >= N_UP[rung - 1]
                and ledger.dwell(rung) >= T_DWELL
                and reserve.certified()
                and not (ledger.compromised & self.RUNGS[rung - 1][1]))

    def invariant_ok(self, rung, state):
        # 污染/降额通道不得出现在不变式中
        return (not (self.RUNGS[rung][1] & state.compromised)
                and self.RUNGS[rung][4](state))
```

```python
class PriorityReservedScheduler:
    def __init__(self, rho0, e_c0):
        self.rho0 = rho0          # C0 预留 CPU 份额
        self.e_c0 = e_c0          # C0 预留能量

    def admit(self, task):
        if task.cls == 'C0':
            return True           # 预留，声明负载下恒可调度
        if task.cls == 'C1':
            return self.slack_cpu() > 0 and not self.c0_overloaded()
        if task.cls == 'C2':
            return (self.slack_cpu() > 0
                    and self.opp_energy() > task.cost
                    and not self.c0_overloaded())
        return False

    def snapshot_read(self):
        return self.ledger.snapshot()   # wait-free：读不可变快照，无锁

    def on_deadline_miss(self, cp):
        return conservative_fallback(cp) # 迟到即保守；禁止迟到提交

    def acquire(self, lock, task):
        # 优先级继承，避免 C2 持锁阻塞 C0
        return lock.acquire(priority_inheritance=task.priority)
```

**正确性定理（Concurrent-Energy Soundness, CES）**
假设 A33–A45（第 57–58 轮）成立；**(A46)** CEL：单调分量构成 join-semilattice（交换/结合/幂等）、非单调算子仅经 SQ 单写者定序、门判定只读已验证快照且陈旧读不解锁；**(A47)** SPC：分支仅在验证谓词 V_b 通过后合并、EV-conc 要求血缘不相交且限 L1、推测能耗只来自 B_opp；**(A48)** EAG：能耗上界 ĉ 与储备下界 E_res 诚实（对热/老化/负载取保守）、能量门与提交原子执行；**(A49)** ERG：能力包络对 b 单调不减、对 θ 单调不增，阶梯不变式成立，升级需恢复证据+驻留+储备证书；**(A50)** PRS：C0 预留算力与能量、快照读 wait-free、截止未达则禁止迟到提交、C2 不挤占 E_C0；**(A51)** PCX++++：所有提交基于一致快照、双门、有界轮次。则：

1. **线性化安全**：任意并发历史 H 的每次提交等价于某个串行执行；第 58 轮失效界增加 δ_conc（OCC 中止/陈旧读重判）与 δ_spec（推测验证漏检）。并发本身不产生新的信任来源。
2. **并发单调性**：对任意交错，有效权限集满足 A_eff(H)⊆A_serial(≤_L)；若某交错使 A_eff 变大，则必存在一个已验证的 SQ 非单调提交作为线性化点——即"放松"永远可归因到一个被显式定序并回读校验的事件。
3. **能量安全与续航证书**：若 e(0)≥E_res(0) 且所有执行动作 a∈A_E，则 P(∀t≤H: e(t)≥E_res(t))≥1−δ_E−δ_th；且规划 H_plan≤H_endur(δ) 时，任务期内发生储备违例的概率 ≤δ_E+δ_th。低电量只会收缩 A_E，不会放宽证据门。
4. **截止、终止与调度**：C0 在声明负载下恒可调度；C1 有界饥饿自由；C2 仅用松弛资源且可抢占；任何截止期错失都导向保守动作而非迟到提交；PCX++++ 在 k_spec+k_probe+k_cons 内有界终止于 {承诺, 绕行, 返航, L2 协商, 安全停}。
5. **部署界**（对检查点取联合界）：

```
P_safe ≥ 1 − Σ_cp (δ_f + ε_meta + δ_probe + ε_h + δ_ood·α_conf + δ_xm·1[L1]
                   + δ_ft + δ_kg + δ_ux + δ_conc + δ_spec + δ_E + δ_deadline)
         − P(C0 被饿死) − P(能耗模型乐观) − P(储备误算) − P(热降额未建模)
```

关键：**CEL 让并发只能收紧**（单调可交换、非单调单写者、陈旧读保守重判）；**SPC 让并发只买延迟不买信任**（验证后提交、血缘不相交、机会预算）；**EAG 让能量成为第二道门**（双门提交、储备分账、续航证书）；**ERG 让低电连续退化而非突然关机**（能力包络、五级阶梯、滞回）；**PRS 让安全关键线程不被并发饿死**（C0 预留 wait-free、迟到即保守）。五者共同把第 58 轮的三条安全单向通道扩展为"并发、能量、时间"三条新的单向约束通道。

## 6. 本轮最大风险

**一句话**：本轮把"并发"和"能量"同时提升为安全论证的前提，最危险的不是单独一项失效，而是二者**复合**——一个乐观的能量模型（漏算热降额/老化/负载）会让推测并发把返航储备花在失败分支上，而一个逃出定序器的非单调更新（陈旧读收窄共形带或升级授权）又会在能量门还来得及否决之前把承诺提交出去；必须以保守能耗上界、硬储备分账、单写者定序、C0 wait-free、迟到即保守五重护栏，宁可少并发、早返航、按时保守放弃，绝不接受"既快又自信、同时没电"。
