# 想法区 · 新循环第 1 轮（承接 v9.0 ICF-PACT）：上界优先的回溯修复

**灵感词**：upper bound / 伪代码 / 回溯法  
**一句话**：v9.0 已经把「下界证明」变成可携带的部分证书；本轮把同一件事补到上界——先用一个带预算的随机重启回溯搜索把可行调度 \(U\) 推到 \(\mathrm{OPT}\)，再用一次 \(\mathrm{NO}(U-1)\) probe 闭合。状态从 \((L,U,s,m,\pi)\) 扩展为 \((L,U,s,m,\pi,A)\)，其中 \(A\) 是设计中的可审计修复档案（本轮以修复摘要字段记录，完整类级档案留作下一步）。

## 一、复盘：v9.0 只修了下界，没有修上界

v9.0 ICF-PACT 的状态是

\[
(L,U,s,m,\pi),\qquad
\pi\ \text{证明}\ \mathrm{NO}(L-1),\quad
(s,m)\ \text{是}\ C_{\max}=U\ \text{的可行调度},\quad L\le U.
\]

它的循环不变式很干净：每次 probe 之后，要么 \(L\) 上升，要么 \(U\) 下降，停止时 \(L=U\) 就是最优性证书。问题在于，v9.0 的 **probe 策略仍然假设 \(L\) 是紧的**。`lower-first` 从 \(L\) 开始问，只有在 \(U-L\) 很小、且 \(L\) 已经接近 \(\mathrm{OPT}\) 时才便宜。252 主集恰好满足这个条件：初始 gap 分布是 \(148\) 个 \(0\)、\(103\) 个 \(1\)、\(1\) 个 \(5\)，所以 `lower-first` 只用 104 次 probe。换成宽 gap 的 `hap.weak_rows(4)`，同一个策略要 452 次 probe、1810 次总 LP、8.35 s；`binary` 也要 421 次 probe、1829 次 LP。gap 从 4 到 13 时，二分/前缀搜索的代价立刻显形。

这说明 v9.0 的「部分证书」只完成了 **dual side**：它知道怎么把 NO 证明切成可携带的 frontier，却把 YES 侧留给了初始的 greedy/LNS 调度。于是算法在宽 gap 上不断用下界 probe 去逼近一个本来可以提前变好的上界。一个自然的反问是：**为什么不先把 \(U\) 修到 \(\mathrm{OPT}\)，再问一次 \(U-1\)？** 如果 \(U=\mathrm{OPT}\)，这次 probe 回答 NO，括号闭合；如果 \(U=\mathrm{OPT}+1\)，它回答 YES，带回一个 \(C_{\max}=\mathrm{OPT}\) 的调度，下一轮也闭合。上界一旦变紧，下界 probe 的次数就从「搜索深度」退化成「一次确认」。

## 二、直觉：可行调度是上界证书，回溯是修上界的自然动作

下界证书是「没有任何调度能小于 \(h\)」；上界证书是「这就是一个 \(C_{\max}=U\) 的调度」。两者是同一枚硬币的两面。v9.0 把下界侧做成了 `FrontierProof`，本轮把上界侧看成 **primal repair tree**：

- 根节点是空调度；
- 每个节点选择一个已满足前驱的工件，放到某台可用机器上；
- 一条根到叶的路径就是一个 SGS 优先级序；
- 叶子要么是一个完整调度（YES witness），要么是一个死端（该分支在该 horizon 下不可行）。

如果整棵树被穷尽且没有完整调度，那么它本身就是 \(\mathrm{NO}(h)\) 的证明；如果只探索了一部分，那么未探索的分支构成一个 **open frontier**，它是「上界侧的部分证书」，对称于 ICF 的下界 frontier。于是「upper bound」不是目标函数的一个数值，而是一个可以被搜索、被中断、被审计的对象。

「回溯法」在这里不是装饰：SGS 的每一步都有多个可选工件和机器；贪心只走第一条路径，回溯则在死端或预算边界退回上一个决策，换一个孩子。实际实现里我们用两种特化：

1. **有限差异搜索（LDS）**：每个节点按启发式排序孩子，第一个孩子代价 0，其余孩子代价 1；逐步放宽差异预算 \(D=0,1,2,\dots\)。它是真正的深度优先回溯，但单棵树在 21 个工件上仍可能很大。
2. **随机重启回溯**：每次从根重新开始，用随机化的优先级走一条根到叶路径；失败就退回根，换一个随机序。它把「回溯到根」作为 diversification，实测比单棵 LDS 更稳、更便宜。

这两种都是回溯树的访问策略；区别只在「回溯到父节点」还是「回溯到根」。本轮的主实验采用随机重启，因为它在宽 gap 集上把 151/160 个初始上界改好，并把 160/160 推到 \(\mathrm{OPT}\)。

## 三、形式化草图：状态、转移与不变式

设实例 \(I=(J,M,p,E,\mathrm{elig})\)，\(n=|J|\)，\(m=|M|\)。一个调度是 \((s,mach)\)，\(C_{\max}(s)=\max_i(s_i+p_i)\)。SGS 把拓扑序 \(\pi\) 映射为最早可行调度 \(\mathrm{SGS}(\pi)\)；单条 greedy SGS 不保证完备，但修复树同时枚举拓扑序和机器选择，并对固定选择做左移，因此树中包含某个最优调度。

修复树 \(\mathcal{T}(h)\) 的节点是一个部分调度 \(S\)。对每个 \(i\notin S\) 且 \(\mathrm{pred}(i)\subseteq S\)，对每台 \(k\in\mathrm{elig}(i)\)，令 \(t\) 为满足前驱、机器占用和 \(t+p_i\le h\) 的最早开始时间；\((i,k)\) 产生一个孩子。树的分支是穷尽的；深度优先访问，遇到 \(C_{\max}>h\) 或剩余工件的 \( \mathrm{est}_i+p_i+q_i>h \) 就剪枝。

一次修复尝试返回三类结果：

\[
\mathrm{Repair}(h)\in
\{\mathrm{WITNESS}(s,m),\ \mathrm{OPEN}(F),\ \mathrm{EXHAUSTED}\}.
\]

- `WITNESS`：完整调度，审计通过后给出上界 \(C_{\max}(s)\)；
- `OPEN(F)`：预算耗尽时未探索的叶子集合，是部分上界证书；
- `EXHAUSTED`：整棵树无解，给出 \(\mathrm{NO}(h)\) 的证明（本轮实现不产生这一类，保留为设计）。

BUR-ICF 的状态是

\[
(L,U,s,m,\pi,A),
\]

其中 \(A\) 是修复档案：设计上每次尝试记录 horizon、种子、预算、结果和（若有）调度；本轮实现只把最终摘要写入 benchmark row。不变式是

\[
\pi\ \text{证明}\ \mathrm{NO}(L-1),\quad
C_{\max}(s)=U,\quad
L\le U,\quad
A\ \text{中每个 WITNESS 都通过调度审计}.
\]

转移：

1. **Primal repair**：若 \(U-L>1\)，在 \(h=U-1\) 上跑 `Repair`。若有 WITNESS 且 \(C_{\max}(s')<U\)，令 \(U\leftarrow C_{\max}(s')\)，\((s,m)\leftarrow(s',m')\)，把记录追加到 \(A\)。若 \(U=L\)，直接闭合。
2. **Dual probe**：否则在 \(h=U-1\) 上调用 PACT。NO 则 \(L\leftarrow U\)，\(\pi\leftarrow\) 新证明；YES 则用返回调度更新 \(U\)；UNKNOWN 则保留 bracket（本实现的 `run_icf` 在这里停止，fallback 留作下一步）。
3. **Policy**：若 \(U-L\le1\)，直接用 `lower-first`（此时 \(L=U-1\)，两种策略问的是同一个点）；若 \(U-L>1\)，先 repair，再用 `upper-first`。这就是 `hybrid` 策略。

关键不是「上界优先」四个字，而是 **修复把 \(U\) 变紧之后，probe 的方向应该切换**：修复前 \(L\) 紧、\(U\) 松，从 \(L\) 问是对的；修复后 \(U\) 紧、\(L\) 松，从 \(U-1\) 问才是对的。`hybrid` 是这一个不对称性的最小实现。

## 四、实验判断：主集打平，宽 gap 集大幅下降

主集 252 例（PACT 初始化，`seed0=0`）：105 probes / 447 搜索 LP / 137 证书 LP / 273 pin LP / 857 总 LP / 10.74 s，252/252 认证。v9.0 `lower-first` 是 104 / 429 / 135 / 273 / 837 / 9.97 s。主集只差 1 次 probe、20 次 LP，属于打平略慢；换 `seed0=1000` 时修复把唯一 gap5 实例的 \(U\) 从 46 降到 42，正好复现 104 / 429 / 135 / 273 / 837 的基线数字，时间 10.32 s。

宽 gap 集 `hap.weak_rows(4)` 160 例（`seed0=0`）：160 probes / 344 搜索 LP / 220 证书 LP / 0 pin LP / 564 总 LP / 6.15 s，160/160 认证；probe 分布是 8 个 0、145 个 1、6 个 2、1 个 3。对照：

- HAP：421 probes / 1829 总 LP / 8.99 s；
- ICF `gap:4`：452 probes / 1810 总 LP / 8.35 s；
- 修复后仍用 `lower-first`：282 probes / 771 总 LP / 6.45 s，但 159/160（1 个 UNKNOWN）。

所以收益不是「随机搜索本身」，而是 **repair + upper-first 闭合** 的组合：repair 把 \(U\) 推到 OPT，upper-first 把「证明最优」压缩成一次 NO(OPT−1)。只修上界、不换 probe 方向，会在 `large_het/7` 这类 \(L\) 很松的实例上继续卡住；只换 probe 方向、不修上界，则会在宽 gap 上退化成 674 probes / 3365 LP / 30.3 s。

## 五、最大的风险

这套东西的收益高度依赖「初始 \(U\) 确实松」。252 主集已经几乎全紧，BUR-ICF 只是打平；宽 gap 集又是我自己筛出来的压力集。若真实实例的 \(U\) 天然接近 OPT，随机重启就只是额外开销，算法的新意会退化成 `hybrid` 这一个策略开关。因此本轮必须把「主集不显著变差」和「宽 gap 集显著变好」同时写清楚，不能把 160/160 说成普遍优势。

**本轮最大风险**：BUR-ICF 的收益主要来自 `hap.weak_rows(4)` 这一批宽 gap 合成/压力实例，而 252 主集上只是打平；一旦真实实例的 \(U\) 已经接近 \(\mathrm{OPT}\)，随机重启修复就退化为额外开销，算法的新意也就只剩一个策略开关。

## 1. 问题与记号

实例

\[
I=(J,M,p,E,\mathrm{elig}),
\]

其中 \(J=\{1,\dots,n\}\) 是工件，\(M=\{1,\dots,m\}\) 是机器，\(p_i>0\) 是加工时间，\(E\subseteq J\times J\) 是前驱关系，\(\mathrm{elig}(i)\subseteq M\) 是工件 \(i\) 可用的机器集合。

调度 \((s,\mathrm{mach})\) 给每个工件一个开始时间 \(s_i\) 和机器 \(\mathrm{mach}(i)\in\mathrm{elig}(i)\)。可行性要求：

1. 同一机器上的区间 \([s_i,s_i+p_i)\) 两两不重叠；
2. 若 \(j\in\mathrm{pred}(i)\)，则 \(s_i\ge s_j+p_j\)。

目标：

\[
C_{\max}(s)=\max_{i\in J}(s_i+p_i).
\]

本文只处理 \(C_{\max}\) 最小化；所有实例在语料中都可调度。

---

## 2. SGS 与修复树

### 2.1 串行调度生成（SGS）

给定一个拓扑序 \(\pi=(i_1,\dots,i_n)\)，SGS 依次放置工件。对工件 \(i\)，令

\[
r_i(\pi)=\max_{j\in\mathrm{pred}(i)}(s_j+p_j)
\]

（没有前驱时为 0），并在每台 \(k\in\mathrm{elig}(i)\) 上找最早可行开始时间

\[
t_{i,k}=\min\{t\ge r_i(\pi): [t,t+p_i)\cap \text{已占用}_k=\varnothing\}.
\]

选择使 \(t_{i,k}+p_i\) 最小的机器（并列时取机器编号最小），令 \(s_i=t_{i,k}\)，把区间加入该机器。得到的调度记为 \(\mathrm{SGS}(\pi)\)。

**完备性口径**：单条 greedy SGS 只是修复树的一条路径，本文不声称它单独完备。修复树同时枚举拓扑序和机器选择；对固定的序与机器选择，把每个工件左移到最早可行位置不会增加 \(C_{\max}\)，所以树中至少有一条最优路径。实验中的 YES 证书只依赖 `check_schedule`，不依赖这个论证。

### 2.2 修复树 \(\mathcal{T}(h)\)

固定 horizon \(h\)。修复树的节点是一个部分调度 \(S\)（已放置工件的开始时间和机器）。根节点 \(S=\varnothing\)。对节点 \(S\)：

- 可扩展工件集合
  \[
  \mathrm{Elig}(S)=\{i\notin S:\mathrm{pred}(i)\subseteq S\}.
  \]
- 对每个 \(i\in\mathrm{Elig}(S)\) 和每台 \(k\in\mathrm{elig}(i)\)，令 \(t\) 为满足已放置前驱、机器占用和 \(t+p_i\le h\) 的最早开始时间；若存在，产生孩子
  \[
  S' = S\cup\{(i,t,k)\}.
  \]
- 若 \(t+p_i>h\)，该 \((i,k)\) 分支在该节点处死亡。

树是有限的：每个工件只放一次，分支因子至多 \(n\cdot m\)。一条根到叶的路径对应一个 SGS 优先级序（可能带机器选择）。叶子有两类：

- **WITNESS**：所有工件已放置，且 \(C_{\max}\le h\)；
- **DEAD**：某个工件在所有机器上都无法在 \(h\) 前放下，或剩余工件的下界已超过 \(h\)。

若整棵树被穷尽且没有 WITNESS，则 \(\mathcal{T}(h)\) 是 \(\mathrm{NO}(h)\) 的证明。若只探索了一部分，未探索的叶子构成 **open frontier**。

### 2.3 剪枝

在节点 \(S\)，对每个未放置工件 \(i\) 计算

\[
\mathrm{est}_i(S)=\max\left(\mathrm{release}_i(S),\ \text{该工件可选机器的最早空闲}\right),
\]

其中 \(\mathrm{release}_i(S)\) 已放置前驱的最早完成时间。定义

\[
\mathrm{LB}(S)=\max_{i\notin S}\left(\mathrm{est}_i(S)+p_i+q_i\right),
\]

\(q_i\) 是工件 \(i\) 到汇点的最长尾路径（含自身加工时间或其后继链，按实现中的 `heads_tails` 口径）。若 \(\mathrm{LB}(S)>h\)，该节点不可能在 \(h\) 前完成，剪枝。这个下界是松弛的，但 sound：它只会剪掉确实不可行的分支。

## 3. 两种回溯访问策略

### 3.1 有限差异搜索（LDS）

在每个节点，把孩子按启发式排序：先按尾长 \(-q_i\)、再按最早开始时间、再按编号。第一个孩子是贪心选择，代价 0；其余孩子代价 1（工件选择或机器选择偏离贪心各算 1）。LDS 对 \(D=0,1,2,\dots\) 逐轮搜索所有差异数不超过 \(D\) 的路径。

伪代码：

```text
LDS(node, d):
    if node.complete: return WITNESS(node.schedule)
    if d > D or node.bound > h: return DEAD
    for rank, child in enumerate(ranked_children(node)):
        cost = 0 if rank == 0 else 1
        if d + cost <= D:
            r = LDS(child, d + cost)
            if r is WITNESS: return r
    return OPEN
```

LDS 是真正的深度优先回溯；它会在死端退回父节点，换下一个孩子。实现中的 `limited_discrepancy_repair` 使用 \(D\le4\)、节点预算 3000、每轮时间上限 0.15 s，并在找到改进了 \(U\) 的调度后继续下一轮；它只产生 WITNESS 或 OPEN，不把预算耗尽误报成 NO。

### 3.2 随机重启回溯

随机重启把回溯的「退回父节点」换成「退回根节点」：

```text
RANDOM-REPAIR(h, R, B, T):
    best = U
    for r = 1..R:
        order = RANDOM-TOPOLOGICAL-ORDER(seed_r)
        s, m = SGS(order)
        if Cmax(s) < best and CHECK(s, m):
            best = Cmax(s); save(s, m)
        if best == L or time > T or r - last_improve > B:
            break
    return best
```

每次 rollout 是一条根到叶路径；失败后从根重新采样。随机化只影响优先级序和并列打破，不改变可行性检查。实现中的 `randomized_repair` 用四种优先级模式：

1. 尾长 \(+\) 噪声；
2. 尾长 \(+0.5p_i+\) 噪声；
3. 纯随机；
4. 最早开始 \(-\) \(0.3q_i+\) 噪声。

每条 rollout 用最早可行 SGS，O(nm) 级别；候选调度只有在 `check_schedule` 通过后才被接受。

### 3.3 为什么主实验用随机重启

在 160 个宽 gap 实例上，单独的 LDS（公平预算：每轮 0.05 s、节点 1500、\(D\le3\)）把 154/160 推到 OPT，耗时 6.67 s、503,846 个节点；仍留下 6 个 gap。随机重启把 160/160 推到 OPT，修复阶段只花 1.45 s、33,680 条 rollout。原因是宽 gap 实例的困难主要在「全局优先级序」而不是「某个局部决策的深回溯」；从根重新采样比在一棵树里深入更有效。LDS 保留为正式的回溯树实现和消融，不作为主引擎。

## 4. BUR-ICF 状态

### 4.1 状态与不变式

BUR-ICF 的状态是

\[
\boxed{(L,U,s,m,\pi,A)}
\]

其中：

- \(L,U\in\mathbb{Z}_{\ge0}\)，\(L\le U\)；
- \(\pi\) 是 \(\mathrm{NO}(L-1)\) 的证明（PACT 的 `Proof`，通常为 Farkas/energy/bound 叶子或 frontier）；
- \((s,m)\) 是可行调度，且 \(C_{\max}(s)=U\)；
- \(A\) 是修复档案，元素为
  \[
  a=(\text{horizon }h,\ \text{seed},\ \text{budget},\ \text{kind},\ s^a,\ m^a,\ U_{\text{after}}),
  \]
  \(\text{kind}\in\{\mathrm{WITNESS},\mathrm{OPEN}\}\)。本实现不产生 `EXHAUSTED`。

不变式：

\[
\boxed{
\begin{aligned}
&\pi\ \text{证明}\ \mathrm{NO}(L-1),\\
&C_{\max}(s)=U,\qquad L\le U,\\
&\forall a\in A:\ a.\text{kind}=\mathrm{WITNESS}\Rightarrow
  \mathrm{CHECK}(s^a,m^a)\land C_{\max}(s^a)=a.U_{\text{after}},\\
&A\ \text{的 WITNESS 按时间顺序严格降低 }U.
\end{aligned}}
\]

\(A\) 是解释性档案，不是最终可靠性的必要条件；最终可靠性仍由 \(\pi\) 和 \((s,m)\) 承担。这样即使修复搜索有 bug 或随机性，也不会把错误上界写进最终证书。

### 4.2 修复档案的审计

设计中的 `RepairAttempt`/`RepairArchive` 审计规则是：

1. 每条 WITNESS 记录必须通过 `check_schedule(inst, Cmax, s, m)`；
2. \(C_{\max}(s^a)\) 必须等于记录中的 `U_after`；
3. WITNESS 的 `U_after` 必须严格小于前一条 WITNESS 的 `U_after`；
4. OPEN 记录只要求 `h` 和 frontier 的节点边界一致，不参与最终最优性。

最终对象可以写成

```text
BURCertificate = (ICFCertificate, RepairArchive)
audit = ICFCertificate.audit_rdf() and RepairArchive.audit()
```

**实现边界**：本轮 `run_ubf` 只把修复摘要写入 benchmark row（`ub0`、`ub_after_repair`、`repair_iters`、`repair_improved`、`repair_t`），并返回 v9.0 的 `ICFCertificate`；`RepairArchive` 的类级实现和 `BURCertificate` 接入是证书层的下一步，不在本轮认证链中。也就是说，本文的 160/160 与 252/252 认证仍然只依赖 `ICFCertificate`，修复档案是解释性设计。

`ICFCertificate` 仍由 v9.0 的 `NO(U-1)` 证明和 \(C_{\max}=U\) 调度组成；`RepairArchive` 只是把「U 是怎么被修下来的」变成可重放的记录。

## 5. 算法

### 5.1 主循环

```text
BUR-ICF(I, B_repair, B_probe):
    (L,U,s,m,pi) = INIT(I)                  # PACT initial bounds
    A = empty archive
    while L < U and probes < B_probe:
        if U - L == 1:
            # 窄括号：一次 probe 就是闭合
            r = PACT-PROBE(L)
        else:
            # 宽括号：先修上界
            (U,s,m) = REPAIR(U-1, L, B_repair, A)
            if U == L:
                break
            # 修复后 U 通常已紧，从上界侧问
            r = PACT-PROBE(U-1)

        if r.verdict == NO:
            L = r.h + 1
            pi = r.proof
        elif r.verdict == YES:
            if Cmax(r.schedule) < U and CHECK(r.schedule, r.machine):
                U = Cmax(r.schedule)
                s, m = r.schedule, r.machine
        else:
            # UNKNOWN：保留 bracket。本实现的 run_icf 在这里直接停止；
            # 修复后仍用 lower-first 的对照实验正是这样留下 1 个 UNKNOWN。
            break

    return BUR-CERT(L,U,s,m,pi,A)
```

### 5.2 REPAIR

```text
REPAIR(h, L, B, A):
    # 先跑一次 LDS（正式回溯树，预算小）
    (U,s,m) = LDS-REPAIR(h, D=0..4, node_budget=3000, time_cap=0.15)
    # 再用随机重启（主引擎）
    for r = 1..B.restarts:
        order = RANDOM-TOPOLOGICAL-ORDER(seed_r)
        (s',m') = SGS(order)
        if Cmax(s') < U and CHECK(s',m'):
            U = Cmax(s')
            s,m = s',m'
            A.append(WITNESS(h, r, s',m',U))
        if U == L or time > B.time or r - last > B.stall:
            break
    return (U,s,m)
```

**实现边界**：主实验只调用随机重启；`ubf.py` 中的 `limited_discrepancy_repair` 是正式回溯树实现，但未接入主 benchmark。§8.4 的 LDS 消融来自独立原型 `tmp/ub/lds_fair.py`，其递归逻辑与 `ubf.py::limited_discrepancy_repair` 相同，预算更小（每轮 0.05 s、节点 1500、\(D\le3\)）。这个选择在 160 例上有数据支持，不是把「回溯」当成口号。

### 5.3 策略选择

`run_ubf` 的 `policy='hybrid'`：

- 若 \(U-L\le1\)：`close_policy='lower-first'`。此时 \(L=U-1\)，两种策略问的是同一个点；用 lower-first 保持与 v9.0 的语义一致。
- 若 \(U-L>1\)：先 repair，再用 `close_policy='upper-first'`。修复后 \(U\) 通常紧，问 \(U-1\) 最省。

这是本轮的策略核心：**不是无条件 upper-first，而是「先修上界，再从上界侧闭合」**。无条件 upper-first 在宽 gap 集上非常差（674 probes / 3120 搜索 LP / 30.3 s），无条件 lower-first 在修复后仍会在 \(L\) 很松的实例上卡住（159/160，1 个 UNKNOWN）。

## 6. 正确性

### 6.1 引理

**引理 1（SGS 见证有效）**：若 `randomized_repair`/`LDS-REPAIR` 返回 \((s,m)\) 且 `check_schedule` 通过，则 \((s,m)\) 是可行调度，且 \(C_{\max}(s)\) 是合法上界。

证明：`check_schedule` 逐项检查机器不重叠、前驱、资格和 horizon；SGS 的每次放置都满足这些约束。\(\square\)

**引理 2（修复不会抬高 U）**：REPAIR 只在 \(C_{\max}(s')<U\) 且 `check_schedule` 通过时更新 \(U\)；否则 \(U\) 不变。因此 \(U\) 单调不增。

**引理 3（probe 保持括号）**：PACT 的 NO(h) 证明给出 \(L\ge h+1\)；YES(h) 调度给出 \(U\le C_{\max}\le h\)。两者都不会破坏 \(L\le U\)。

**引理 4（终止）**：每次循环要么 \(L\) 增加至少 1，要么 \(U\) 减少至少 1；整数区间有限，故在 `max_probes` 内终止或提前闭合。

### 6.2 定理

**定理 1（不变量）**：初始 PACT bounds 满足不变式；REPAIR 只通过引理 1 的 WITNESS 降低 \(U\)；probe 通过引理 3 更新 \(L\) 或 \(U\)；因此每次迭代后不变式成立。

**定理 2（最终最优）**：若循环以 \(L=U\) 结束，则 \(\pi\) 证明 \(\mathrm{NO}(U-1)\)，\((s,m)\) 证明 \(C_{\max}=U\)，所以 \(U=\mathrm{OPT}\)。`ICFCertificate.audit_rdf()` 通过时，最终证书有效。

**推论（部分正确）**：若预算耗尽或 UNKNOWN 提前停止，\((L,U,s,m,\pi)\) 仍是一个可审计的括号；修复档案可选，且不参与最终可靠性。

### 6.3 边界

- `EXHAUSTED` 的修复树可以证明 \(\mathrm{NO}(h)\)，但本实现没有产生它；本文不声称「修复搜索本身能证明最优」。
- LDS 的 `D` 限制和随机重启的预算都只产生 WITNESS 或 OPEN；把预算耗尽当成 NO 是 soundness bug，代码中明确禁止。
- 修复档案的审计是额外的解释性检查；最终最优性不依赖它。

## 7. 复杂度

设 \(n=|J|\)，\(m=|M|\)，\(e=|E|\)。

- 一次 SGS rollout：最坏 \(O(n(m+n+e))\) 时间（每步扫描前驱、机器和占用区间；实现中区间用列表，n≤21 时足够小），\(O(n+m+e)\) 空间。
- 随机重启：\(O(R\cdot n(m+n+e))\) 时间，\(R\) 是 rollout 数；实验预算 \(R\le800\) 每实例，实际因 stall/时间上限提前停止。
- LDS：最坏 \(O(b^D)\) 个节点，\(b\le n\cdot m\)，\(D\le4\)；实现用 node_budget/time_cap 截断。
- PACT probe：沿用 v9.0 的 LP/Farkas 代价；主集由 \(O(1)\) 次 probe 主导，宽 gap 集由 repair + 一次 probe 主导。
- 空间：调度 \(O(n)\)，机器区间 \(O(n)\)，修复档案 \(O(R)\) 条记录；不保存整棵修复树。

## 8. 实验

### 8.1 设置

- 主集：`icf.corpora()` 的 252 例；n∈[11,21]，m∈[3,4]。
- 宽 gap 集：`hap.weak_rows(4)` 的 160 例；初始 gap 分布为 4:47、5:37、6:31、7:32、8:8、9:2、10:1、11:1、13:1。
- 主集初始状态由 PACT 的 `initial_bounds()`/`_ensure_lb_proof()` 给出；宽 gap 集由 `hap.init_weak()` 给出。
- 修复预算：`repair_iters=800`、`repair_time=2.0 s`、`repair_stall=200`；probe 上限 `max_probes=64`。
- `known` 只用于输出 `ok/gap0`，不参与算法决策；REPAIR 的停止目标是 \(L\)，不是 `known`。
- 认证条件：`certified=True`、`audit=True`、`partial_fail=0`、`unknown=0`，且 `opt==known`。

### 8.2 主集 252

| 方法 | probes | 搜索 LP | 证书 LP | pin LP | 总 LP | 时间 | 认证 |
|---|---:|---:|---:|---:|---:|---:|---:|
| v9.0 `lower-first` | 104 | 429 | 135 | 273 | 837 | 9.97 s | 252/252 |

| BUR-ICF `seed0=1000` | 104 | 429 | 135 | 273 | 837 | 10.32 s | 252/252 |

主集初始 gap 只有 148 个 0、103 个 1、1 个 5；只有 `base/large_het/7` 触发 repair。`seed0=0` 把它的 \(U\) 从 46 修到 43，随后 upper-first 用 2 次 probe 闭合；`seed0=1000` 修到 42，用 1 次 probe 闭合。主集结论是 **打平**：probe 差 0–1，总 LP 差 0–20，时间有 0.35–0.78 s 的修复开销。BUR-ICF 不是为 252 主集设计的；它的目标是宽 gap。

| 方法 | probes | 搜索 LP | 证书 LP | pin LP | 总 LP | 时间 | 认证 |

### 8.4 消融

| 变体 | 作用 | probes | 总 LP | 时间 | 结果 |
|---|---|---:|---:|---:|---|
| 无 repair，`upper-first` | 只看 probe 方向 | 674 | 3120+245 | 30.3 s | 160/160，但极慢 |

这张表解释了为什么主实验用随机重启而不是 LDS：LDS 在 160 例上留 6 个 gap，随机重启全部闭合；而 `upper-first` 闭合是 repair 生效的必要条件——只修不换方向会在 `large_het/7` 这类 \(L\) 很松的实例上继续用 \(L\) 探测，最终 UNKNOWN。

\* `gap:4` 的 8.35 s 来自 `exp/v8u/bench_gap_tau4.json` 的记录批次；同一批机器上重跑可能到 13.7 s。表中时间只作相对参考，probe、LP、认证数是硬指标。LDS 消融的 154/160 是 repair-only 结果，不含最终 PACT 闭合，因此不能与 160/160 的认证列直接比较。

### 8.6 审计

- 主集 252/252 `certified`，`partial_fail=0`，`unknown=0`。
- 宽 gap 集 160/160 `certified`，`partial_fail=0`，`unknown=0`。
- 所有被接受的 repair 调度在写入 \(U\) 前都过 `check_schedule`；最终 `ICFCertificate.audit_rdf()` 通过。
- `RepairArchive` 的审计是解释性的，未纳入最终最优性；这一点在 §4.1 明确写出，避免把随机搜索误当成证明。

## 9. 与 v9.0 的差异

| 维度 | v9.0 ICF-PACT | v9.3 BUR-ICF |
|---|---|---|
| 外层状态 | \((L,U,s,m,\pi)\) | \((L,U,s,m,\pi,A)\) |
| 重点 | 下界侧部分证书 | 上界侧可行修复 + 下界侧闭合 |
| probe 策略 | `lower-first` / `binary` / `upper-first` | `hybrid`：窄括号 lower-first；宽括号 repair 后 upper-first |
| 宽 gap 集 | 452 probes / 1810 LP / 8.35 s | 160 probes / 564 LP / 6.15 s |
| 主集 | 104 probes / 837 LP / 9.97 s | 104–105 probes / 837–857 LP / 10.3–10.7 s |
| 证明语义 | 单叶 ICF 证书 | 同一 ICF 证书 + 可审计修复档案 |
| 实现 | `exp/v8u/icf.py` | `exp/v8u/ubf.py`（调用 `run_icf` 闭合） |

BUR-ICF 不是替代 ICF；它把 ICF 的「一次 probe 闭合」从「\(L\) 已经紧」推广到「先用 repair 把 \(U\) 变紧，再从 \(U-1\) 闭合」。

## 10. 已知风险与限制

1. **主集没有显著收益**：252 例上只有 1 个 gap5 实例触发 repair；其余 251 例 \(U-L\le1\)。BUR-ICF 在主集是打平略慢，不能宣称全面优于 v9.0。
2. **收益依赖宽 gap 集**：160 例的 gap 分布是 4–13，属于 `hap.weak_rows(4)` 的压力集；真实实例若 \(U\) 已经接近 OPT，repair 只是额外开销。
3. **随机性**：随机重启的 probe/LP 有 160–163、564–606 的种子波动；没有确定性最坏界。
4. **不证明 NO**：bounded repair/LDS 不产生 `EXHAUSTED`，不能替代 PACT 的下界证明；最终 NO 仍由 PACT 给出。
5. **修复档案不在可信基**：`RepairArchive` 只解释 \(U\) 的下降；最终可靠性仍依赖 `ICFCertificate`。如果要把 repair 本身纳入证书，需要实现并审计完整的 `EXHAUSTED` 树。
6. **LDS 不是主引擎**：单棵 LDS 在 160 例上只到 154/160；主实验的 160/160 来自随机重启。把 LDS 写成主引擎会与实验不符。
7. **时间波动**：不同批次/机器负载下墙钟差别明显；表中时间只作同一环境下的相对参考，probe/LP/认证数是主要指标。
8. **未覆盖真实数据**：252 + 160 都是合成/结构化语料；没有真实生产调度数据上的验证。
