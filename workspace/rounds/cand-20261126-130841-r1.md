## 1. 两个灵感的第一性原理

### 灵感 1 ·「实例分割」→ 把实体从「框」变成「像素级身份」，直接拔掉第 3 轮最大风险

第 3 轮把状态层补上了，但实体是**框级**的（U16 的档案吃检测框）。框级表示有三个隐性缺陷，恰好对应三类失败：

- **框内混入干扰物 → 身份交换（bind swap）**：目标框里同时罩着干扰物时，中心距/最近邻关联会把干扰物判成目标的"延续"——这就是第 3 轮 §5 的「地图毒化」，绑定错误让整条路标链在错误锚点上"自信地失败"。
- **框面积无法表达遮挡**：遮挡与否只能靠检测置信度间接猜；而遮挡轴恰恰是五个泛化轴之一。
- **框丢失形状 → 供抓性只能靠外观先验**：抓取候选排序退化为"看起来像什么"，而不是"几何上好不好抓"。

实例分割把这三个缺陷逐个变成可测量量：

- **身份 = 像素集合**：绑定用掩码 IoU + 匈牙利关联，身份交换需要掩码实际重叠，而不是框重叠（L14）。掩码边界误差远小于物体尺度时，绑定错误从"框交叠概率"降为"边界误差"问题——这是对第 3 轮头号风险的结构性解药，而非概率性缓解。
- **遮挡 = 可见率 ρ**：`ρ_e = |M_e ∩ visible| / |M_e|` 是连续量，直接喂 IP-15 的遮挡事件与 IP-04 的上下文特征，阈值第一次有物理含义。
- **抓取 = 掩码几何**：形状/主轴/宽度直接生成按几何供抓性排序的抓取候选（IP-14 档案的升级）。
- **滑移 = 掩码漂移**：运输相位上目标掩码相对夹爪参考系的微位移，比通用光流更抗背景干扰（IP-14 的 SlipGuard v2）。

**但实例分割不是免费的午餐**，必须诚实标注三条新增风险：①开放词表实例分割在相似实例间的**身份交换**；②接触/高速运动/运动模糊下**掩码边界漂移**；③分割算力远高于检测，直接冲击 U12 延迟预算。因此配套**掩码质量门（U20）+ 事件/相位触发调度（L16）**，质量不达标就退化为框级（Level-1.7），绝不让"更精细的感知"变成"更自信的错误"。

### 灵感 2 ·「自适应控制」→ 新语料把「固定增益伺服」的隐含假设打破了

第 2 轮把"最后一厘米"交给了伺服，第 3 轮又给伺服喂了融合状态；但伺服本身始终是**固定增益 K**。固定增益隐含一个假设：被控对象的局部动力学在训练分布内。新语料恰好打破它：

- **装凳子（Assemble_Stool）**：紧配合、接触阶段刚度突变、需要力/位混合的柔顺。固定增益在"自由空间 → 接触"的刚度阶跃上会过冲或卡死。
- **叠衣服（Fold_Clothes）**：可变形、位形连续变化、无固定 SE(3) 位姿。位姿+协方差的刚体状态（U16）根本不足以表示布料。

自适应控制提供三件事，且都可以做成**现成件、可证伪**：

1. **在线辨识局部增益**：从跟踪误差的持续方向性/振荡中估计真实增益相对名义值的偏差 Δ（不需要显式系统辨识，用归一化 MIT 规则/递推最小二乘即可）。
2. **相位增益调度**：reach 用中增益高阻尼、grasp 用高刚度、transport 用高刚度抗滑移、insert/release 用**低刚度柔顺**——相位本身就是最强的先验（U23）。
3. **安全包络**：增益必须 clip 在 `[K_min, K_max]`、带死区防噪声漂移、并保留固定增益回退；无界自适应禁止上线（P14）。

**最关键的诚实边界**：自适应要"看见"失配才有用，而激励（主动试探/持续误差）要花步数（P12 的账），噪声又会通过自适应律注入方差。因此本轮给出选择规则（L15）：**只有当模型失配的幅度显著大于噪声诱导的方差下限时，自适应才占优**；否则默认固定增益 + 仅相位调度。这把"自适应控制"从一句口号变成了可预注册的开关判据。

### 灵感合流 · 感知-控制共设计：分割喂控制，控制约束分割

两个灵感不是并列关系，而是**互为接口**：

- **分割 → 控制**：掩码漂移提供滑移/接触信号，供自适应律判断"手上物体是否还是同一实例、是否正在滑、被遮挡多少"；没有这条信号，自适应只能盲调。
- **控制 → 分割**：相位切换/事件（断言失败、大光流、滑移报警）触发重分割，而非常规每步跑——这是把 L16 的延迟预算真正闭合的唯一办法。
- **可变形任务暴露 U16 的刚体假设不足**：当形状方差主导位姿方差时（L17 的方差分解检验），必须升级为部件/关键点表示（IP-18，条件启用，由 F4 触发但不预设结论）。

## 2. 研究问题（新增 Q13–Q15，接第 1–3 轮 Q1–Q12）

- **Q13（实例分割可靠性）**：开放词表实例分割在 32 项任务 + 新 Dex1 长程任务上，身份交换率与边界误差能否把目标绑定错误从第 3 轮框级压到 ≤0.5%？遮挡可见率 ρ 的估计误差能否 ≤0.05？（E634）
- **Q14（自适应控制的收益-稳定性）**：有界自适应伺服在未知负载/接触刚度/可变形下，能否降低调节步数与过冲且零失稳？按 L15 的偏差-方差判据，自适应相对固定增益+相位调度的净收益何时为正？（E636）
- **Q15（可变形/部件表示的必要性）**：在 Fold_Clothes / Assemble_Stool 上，刚体位姿+协方差与部件图表示谁的长程失败率更低、代价可接受？方差分解判据（L17）能否在训练前就预测该用哪种表示？（E639）

## 3. 设计原则（新增 P13–P15，接第 1–3 轮 P1–P12）

- **P13（分割即身份）**：掩码质量门通过时，实体身份以实例掩码为唯一权威表示，禁止框级绑定；质量不达标按退化链降到框级（Level-1.7），不得静默使用低质量掩码。
- **P14（自适应必有界）**：任何在线自适应必须具备 clip 增益盒、死区、以及固定增益回退；无界或不可回退的自适应禁止进入提交路径（安全硬约束）。
- **P15（激励记账）**：需要激励的辨识/探测必须过 P12 的步数账；不可逆相位（接触之后的 insert/release）禁止主动激励，只允许被动观测。

## 5. 本轮最大风险

**「假自信」的感知-控制耦合**：掩码质量门在接触/高速运动/运动模糊下可能**系统性高估**自身质量（因为遮挡与模糊常同时出现，模型会把"看不清"误当作"平滑边界"），于是自适应控制器在错误状态上得到错误的滑移/接触信号，反而"优雅地发散"——这比固定增益的硬碰硬更危险，因为错误被闭环放大而非暴露。对冲：①质量门必须在接触/大光流场景单独标定，而不是在静态帧上标定；②`q < τ_q` 时强制固定增益、禁止自适应；③不稳定性看门狗（振荡/发散检测 → 冻结 K 并回退）与分割前端**解耦**，不共享置信度。次要风险：身份交换（多帧一致 + 接触几何校验）、激励吃步数（P15 白名单 + L15 开关）、可变形表示爆炸（L17 方差检验 + IP-18 条件启用）。

## 3. 新增 IP 详述

### IP-16 · InstanceMaskFrontEnd 实例掩码前端（P0，新）

- **动机**：第 3 轮状态层的实体是框，框内混入干扰物直接导致「地图毒化」；框也无法表达遮挡与形状。掩码把身份、遮挡、形状、滑移统一成一个像素级原子，且几乎是所有下游模块的公共依赖。
- **与现有方案差异**：teaser 榜（待复核假设）与主流 VLA 均以图像/框为输入，无显式实例身份；本方案只在**关键帧/事件**上跑开放词表实例分割，用质量门决定是否信任，因此不是"每步都跑大分割模型"，而是"把分割放在信息增益最高的时刻"。
- **技术可行性**：高。开放词表实例分割（如 SAM 系 + 开放词表检测）与匈牙利关联均为成熟件；质量门是轻量打分器；无需训练新大模型。
- **资源**：数据=IP-06 已有阶段标注导出掩码（半自动：检测框 + 分割细化）；算力=小到中（关键帧）；接口=无新增字段（策略内部）。
- **落地步骤**：①从 IP-06 标注导出掩码 schema（U19）；②开放词表实例分割 + 质量门（U20）最小实现；③掩码关联/匈牙利 + 多帧一致（U21）；④输出 `{M_e, c_e, ρ_e, drift_e}` 给 IP-13/14/15；⑤mask-gated 调度（L16）与延迟实测（E637）；⑥接触/模糊场景专项标定质量门（E634）。
- **风险**：相似实例身份交换（多帧 + 接触几何兜底）；接触/模糊边界漂移致质量门误判（P13 退化 + 独立看门狗）；分割算力冲击延迟（关键帧调度 + E637 门槛）。

### IP-17 · AdaptiveServo 有界自适应伺服（P1，新）

- **动机**：新语料 Assemble_Stool（接触刚度突变）与 Fold_Clothes（可变形）明确超出固定增益的分布；固定增益在这些任务上振荡/过冲，直接吃掉步数分与成功率。
- **与现有方案差异**：不是在策略层加自适应，而是**只改接地层的伺服增益**：以相位为强先验（U23），以跟踪误差方向性/振荡作为失配探测器（L15 开关），在线微调增益并严格 clip；默认仍是固定增益，自适应只在"模型失配显著大于噪声"时开启。
- **技术可行性**：中高。归一化 MIT 规则/递推最小二乘估计局部增益是经典控制件；难点在**稳定性保证**与**与视觉延迟的耦合**，故必须配 clip/死区/看门狗。

## 5. 符号与定义（新增 U19–U24；U1–U18 沿用第 1–3 轮）

- **定义 U19（实例掩码实体）**：实体 e 在 t 时刻表示 `E_e^t = (M_e^t, c_e^t, ρ_e^t, b_e^t)`，M_e∈{0,1}^{H×W} 为实例掩码，c_e 为置信度，`ρ_e = |M_e ∩ visible| / |M_e|` 为可见率，b_e 为边界不确定性。身份由跨帧关联维持。
- **定义 U20（掩码质量门）**：`q(E_e) = σ(wᵀ φ_b + b)`，φ_b 含：开放词表判别边际、相邻帧掩码 IoU 一致性、边界梯度锐度、面积稳定性；门控：`q ≥ τ_q` 才以掩码为身份权威，否则退化框级（Level-1.7）。
- **定义 U21（掩码关联）**：跨帧分配 `π = argmin Σ_e [1 − IoU(M_e^t, M_{π(e)}^{t−1}) + λ_c(1 − c_e)]`，匈牙利求解；身份需连续 N 帧一致 + 位移连续才确认。
- **定义 U22（有界自适应伺服）**：控制 `u_t = K_t e_t + u_ff`；增益更新 `K_{t+1} = clip(K_t + η·ψ(e_t, ẏ_t), K_min, K_max)`，ψ 为归一化 MIT 方向（死区 `|e|>δ` 才更新）；当 `|K_t − K0| > ΔK_max` 或看门狗触发时回退 `K_t ≡ K0`。
- **定义 U23（相位增益调度）**：相位 `p ∈ {reach, grasp, transport, insert, release}`，名义增益 `K0(p)`；reach=中增益高阻尼、grasp/transport=高刚度、insert/release=低刚度柔顺；自适应只在 K0(p) 上叠加有界残差。
- **定义 U24（可变形部件实体）**：当实体无法由单一 SE(3) 描述时，表示为 `D_e = (M_e, {k_j}, G)`，{k_j} 为关键点/部件中心，G 为部件邻接图；由 L17 判据决定是否启用。

## 7. 推导（新增引理 L14–L17；L1–L13 沿用第 1–3 轮）

**引理 L14（掩码绑定支配框绑定）** 设目标 T 与干扰 D 的实例掩码不相交，但 D 的框覆盖 T 投影中心的比例为 f∈[0,1]。框级关联（中心距/最近邻/IoU 排序）在 D 落入 T 框邻域时存在身份交换，其概率满足 `P_swap^bbox ≥ f·(1−ε_det)`（ε_det 为漏检率）；掩码级关联要交换身份，必须两掩码像素重叠或边界误差 ε_b 造成交叠，故 `P_swap^mask ≤ c·ε_b/√A_T`（A_T 为目标像素面积，c 为常数）。⇒ 当 f 显著且 ε_b 远小于物体尺度时，掩码绑定严格优于框绑定，且误差随分割精度可控下降。这正是第 3 轮「地图毒化」风险的结构性缓解：绑定从"框重叠"问题降为"边界误差"问题。∎

**引理 L15（自适应 vs 固定增益的偏差-方差选择）** 设真实局部增益 `K* = K0 + Δ`。固定增益的稳态跟踪幅值 `A_f ≈ |Δ|/(1−ρ)`（ρ 为闭环压缩因子）。有界自适应以速率 η 在线估计：偏差项随 `exp(−ηt)` 衰减，噪声注入的增益方差下界 `Var(K) ≈ c·η·σ²`（σ 为测量噪声），故调节步数 `N(η) = N_bias(η) + N_noise(η)`。存在 η 使 `N_adaptive < N_fixed` 当且仅当失配显著超过噪声下限：`|Δ|/K0 > κ·σ·√(1/η)`。⇒ **自适应只在"模型失配 ≫ 噪声诱导下限"时占优**；这给 IP-17 一个可预注册开关：默认固定增益，仅当失配探测器给出持续方向性/振荡证据时开启。∎

**引理 L16（掩码门控延迟预算）** 设每步预算 B，分割耗时 t_s，检测耗时 t_d ≪ t_s，分割执行率 r（每步概率），则期望步时延 `E[t] = r·t_s + (1−r)·t_d`。要求 `E[t] ≤ 1.2B` 即 `r ≤ (1.2B − t_d)/t_s`。若共 M 个相位、每相位边界强制一次分割、平均相位长 L 步，则 `r ≈ M/L`。⇒ 由相位长度与分割耗时可直接算出**可行任务长度**，E637 用它在不改模型的前提下判定 mask-gated 调度是否踩线。∎

**引理 L17（可变形表示的启用判据）** 设实体内形状方差 `Σ_shape`、位姿协方差迹 `tr(Σ_pose)`。若 `tr(Σ_shape) > κ·tr(Σ_pose)` 且刚体预测残差检验在水平 ε_track 下被拒绝，则位姿+协方差的预测残差无法由位姿不确定度解释，单一 SE(3) 表示欠定，必须升级为部件/关键点表示（U24）。⇒ IP-18 的启用判据是**可检验的方差分解**，而非任务名；Fold_Clothes 属此列，但若 E639 未拒绝刚体则取消。∎
