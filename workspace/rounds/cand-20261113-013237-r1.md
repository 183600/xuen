# 第 64 轮（承接第 63 轮「LIRO 几何-技能-干扰三层闭环」IP-193~202；灵感循环 II 第 3 轮；本轮灵感：「对话管理」×「用户体验」）

> 第 63 轮把 ROSE 升级为 LIRO：LSF 提供几何先验、USL/CSP 提供技能抽象、DIR/AIC 提供四类干扰免疫，并用 J_liro 把几何、技能、干扰三层证书串起来。但第 63 轮的自述风险仍停留在「几何幻觉会污染物理先验」。换到「对话管理 × 用户体验」的视角看，LIRO 还暴露了**三个交互层根基性短板**：
> 1. **DMS 只是单轮意图解析器，不是对话管理**：LIRO 的 DMS 把一句指令解析成逻辑目标 G，`ask_clarify` 只是 Shield 的异常分支。它没有对**目标、指代、约束、权限、能力**的跨轮信念，没有澄清的**价值判断**，也不会处理用户纠正、混合主动、上下文省略与指代漂移——「对话管理」要求系统在多轮中维护并更新信念，而不是每轮重解析。
> 2. **「用户体验」完全缺席**：J_liro 是机器可读证书，不是人可理解的保证；确认频率、解释深度、自主权等级都是固定超参。结果是**过度信任**（用户看到「证书有效」就放手，实际只保证安全不保证任务成功）与**信任不足**（解释太技术化、反复确认导致疲劳）并存；同时没有认知负荷、感知延迟、可控性、可中断性这些 UX 约束。
> 3. **交互决策与安全证书解耦**：澄清、解释、等待、接管都发生在 LIRO 之外，既不进入 J_liro，也不保证「交互层只收缩安全动作集」——一次不恰当的澄清可能让机器人在危险位置停住，一次过度自信的解释可能让用户错过接管窗口。

## 0. 直觉与动机

**灵感 1（对话管理 → DST-G + DAP：从「意图解析」到「安全感知的信念管理」）**
直觉：对话管理的核心不是生成更漂亮的话，而是**在部分可观测下维护一个可用于决策的信念**。把 LIRO 的 `(φ̂, r, ρ_rob, ρ_dir, 技能可行性, 证书有效期)` 直接注入对话状态，让系统同时相信三件事：用户想要什么（goal）、用户指的是哪个物体/区域（referent）、当前机器人**能安全地做什么**（capability）。于是对话状态不再是 `b(goal)`，而是
`b_t ∈ Δ(𝒢 × ℛ × 𝒞 × 𝒫) × 𝒦`，
其中 `𝒦` 是 J_liro 诱导的能力状态（有效/失效、鲁棒裕度、可行技能集）。DST-G 用语言、手势、 gaze、LiDAR 几何与 SSB 场景指纹做** grounding**；DAP 在信念上选择对话动作 `{confirm, clarify, explain, warn, propose, defer, execute, revoke}`，而不是只输出一句「请再说一遍」。

**灵感 2（用户体验 → UXM + UXC：把信任校准写成约束，而不是事后问卷）**
直觉：UX 不是「界面好看」，在这类人机协作操作里，UX 的核心是**信任校准 + 认知负荷 + 可控性 + 感知延迟**。用户对机器人的信任 `τ_t` 应当逼近系统的真实可靠度 `R_t`（由 J_liro 与 CSB 历史成功率给出置信下界），而不是逼近「机器人说话有多自信」。过度信任 `τ > R + δ` 会诱发危险放手，信任不足 `τ < R − δ` 会造成不必要干预和疲劳。UXM 从响应延迟、纠正率、打断、话语长度、注视与显式评分在线估计 `(expertise, load, trust, preference)`；UXC 把这些写成**可验证契约**（确认次数上限、感知延迟上限、解释充分性、接管延迟上限），并规定**安全地板**：任何 UX 优化不得使 J_liro 失效。

**灵感 3（合流 → CURIO：对话-体验双闭环的通用鲁棒操作）**
直觉：把对话管理、用户体验与 LIRO 咬合成一个闭环：**DST-G 维护安全感知信念 → VCO 只在「澄清的期望信息价值 > 交互成本」时发问 → DAP 在安全约束下选对话动作 → XCERT 把 J_liro 翻译成忠实、可理解、按需深度的解释 → TCA 根据信任校准与风险动态调整自主权 → HOC 保证人类接管始终有安全备份 → CSB 把误解、过度信任、疲劳、重复澄清记为可复用交互场景 → OCB-UX 在交互预算下调度对话/解释/自主权模式**。一句话：**LIRO 保证「机器做得到且安全」，CURIO 保证「人知道它为什么、何时该信、何时该接管，并且系统不因交互而变不安全」**。

**灵感 4（LIRO 组件的原位升级）**
- **DMS → DST-G**：单轮意图解析升级为跨轮 grounding 信念跟踪，能力分量直接由 J_liro 注入。
- **Shield → Shield-D（Dialogue-aware Shield）**：技能前置条件投影之外，增加**对话动作前置条件**：不安全时只能 `warn/defer`，不能 `execute`；歧义未消解时不能静默执行高风险技能。
- **SSB → CSB (Conversational Scenario Bank)**：场景签名增入误解类型、澄清历史、纠正类型、信任校准误差、认知负荷，把交互失败也纳入场景进化。
- **J_liro → J_curio**：在物理-几何-干扰证书外，增加对话信念新鲜度、UX 契约满足、解释忠实性、接管通道就绪度。
- **OCB-Skill → OCB-UX**：臂空间从「技能/推理预算」扩为「交互风格 × 自主权等级 × LIRO 模式」，奖励中显式扣除交互成本与信任校准损失。

**灵感 5（一个关键设计原则：交互层只能收缩安全集）**
直觉：对话管理和 UX 优化很容易「为了流畅而放松约束」。CURIO 采用**单调安全原则**：交互层可以因为歧义、低信任、高负荷而**拒绝执行、要求确认、降级自主权**，但永远不能因为「用户说没关系」而扩大 LIRO 的安全动作集。这样，第 63 轮的几何/技能/干扰证书仍然是唯一的安全来源，交互层只做「安全动作集的子集选择 + 人因调节」。

## 1. 形式化定义（增量：定义 201–216）

- **定义 201（CURIO 闭环）**：CURIO = (LIRO, DST-G, DAP, VCO, UXM, UXC, TCA, XCERT, CSB, HOC, OCB-UX, J_curio)。定位：在第 63 轮 LIRO 骨架上挂载「对话状态管理 × 用户体验契约 × 人因安全」交互层；不推翻任何既有接口，只新增语义流组件与一条实时「交互安全门」。
- **定义 202（DST-G 安全感知对话状态）**：`b_t ∈ Δ(𝒢 × ℛ × 𝒞 × 𝒫) × 𝒦`，其中 `𝒢` 为目标，`ℛ` 为指代（物体/区域/接触面），`𝒞` 为约束（时间、力、禁触区），`𝒫` 为权限（是否允许高风险动作），`𝒦 = (valid, ρ_rob, ρ_dir, ℱ_feas, ttl)` 为 J_liro 诱导的能力状态；`ℱ_feas` 为当前鲁棒可行技能集。更新 `b_{t+1} ∝ Z(o_t, a_t)·T(b_t, a_t)`，观测含语言、手势、gaze 与几何 grounding。
- **定义 203（Grounded Referent Posterior）**：`P(r | l_t, P_cloud, SSB) ∝ P(l_t | r)·exp(β·sim(E_txt(l_t), E_geo(obj_r)) + γ·sim(fp_cloud, fp_r))`，其中 `E_txt` 为语言编码器、`E_geo` 为第 63 轮 LSF 几何编码器、`fp_r` 为 CSB 场景指纹；输出每个候选指代的后验与决策 margin `m_ref = p_(1) − p_(2)`。
- **定义 204（DAP 安全约束对话策略）**：`π_d: b_t → Δ(𝒜_d)`，`𝒜_d = {confirm, clarify, explain, warn, propose, defer, execute, revoke}`。硬约束：① `execute` 仅当 `b_t.𝒦.valid` 且技能前置条件成立；② 风险高于 `r_warn` 时必须 `warn`；③ 信任校准误差 `|τ − R| > δ_o` 或用户显式询问时必须 `explain`；④ 无安全可行技能时只能 `defer/revoke`。目标为约束 POMDP：`max E[Σ γ^t(U_task + U_ux − λ_c C_int)]`，s.t. 上述硬约束。
- **定义 205（VOI 澄清）**：对候选问题 `q`，`VOI(q) = E_{a∼Z(q)}[max_{a'∈𝒜_exec} U(a', b^q_a)] − max_{a'∈𝒜_exec} U(a', b) − c_ask(q)`；仅当 `VOI(q) > 0` 且澄清预算未耗尽时发问。`c_ask(q)` 含用户响应时间、打断成本与认知负荷增量；`U` 含任务成功、信任校准、解释充分性与可控性。
- **定义 206（UXM 用户状态）**：`u_t = (e_t, ℓ_t, τ_t, p_t) ∈ [0,1]^4`：专长、认知负荷、信任、偏好；观测 `y_t` 含响应延迟、纠正率、打断、话语长度、注视、显式评分；贝叶斯/卡尔曼更新 `u_{t+1} = u_t + K_t(y_t − h(u_t))`。真实可靠度 `R_t` 由 J_curio 与 CSB 同类场景的 conformal 下界给出；信任校准误差 `Δτ_t = |τ_t − R_t|`，过度信任 `τ_t > R_t + δ_o`，信任不足 `τ_t < R_t − δ_u`。
- **定义 207（UXC 用户体验契约）**：`UXC = (L_max, N_max, E_min, Δτ_max, C_max, T_override)`：感知延迟上限、每任务确认/澄清次数上限、解释充分性下限、信任校准误差上限、认知负荷上限、接管延迟上限。`π_ux` 可行 ⇔ 所有指标满足契约 ∧ `Valid(J_liro)`（安全地板）。
- **定义 208（TCA 信任校准自主权调节）**：自主权 `α ∈ {0,1,2,3}`（逐步确认 / 关键确认 / 通知 / 自主）。`α_t = max{α: LCB_β(R_t, α) ≥ R_min(α) ∧ Δτ_t ≤ δ_o ∧ Valid(J_liro)}`，其中 `LCB_β` 为可靠度的置信下界；升级需连续 `n_up` 次无事故与低纠正率，降级在一次事故/用户纠正后立即触发（迟滞）。
- **定义 209（XCERT 证书解释）**：`e = XCERT(J_curio, u_t)`，解释空间为模板/结构化 claims 的有限集；每个 claim 必须由 J_curio 字段蕴含。解释忠实性 `F(e,J)=1` 当且仅当所有 claim 有证书支撑；解释选择 `e* = argmax_e E[KL(P(τ|e) || P(τ))] − c_exp(e)`，即最大化对用户风险信念的信息增益并扣除解释成本。
- **定义 210（解释充分性）**：`E_suff = 1` 当且仅当用户在解释后对「任务成功率下界、主要风险、何时应接管」三项的理解测试均通过；用短测验或校准问题估计，而非仅看自评分。
- **定义 211（CSB 对话场景银行）**：场景签名扩为 `scene_sig = (V_sig, T_sig, fp_cloud, φ_sig, dyn_annot, d_sig)`，其中 `d_sig = (intent_confusion, clarify_history, correction_type, Δτ, ℓ, α)`。Mine 以「误解/重复澄清/过度信任/高负荷」为交互险情；Mut 增加改写、歧义注入、用户类型切换（新手/专家/急躁）与解释风格变异。
- **定义 212（HOC 人类接管契约）**：接管命令 `o_t ∈ {continue, stop, retreat, take_over}`，检测延迟 `≤ T_override`；接管窗口内执行预计算备份控制器 `K_backup ∈ 𝒦_safe`。高风险动作需显式 consent token `c_t`（带过期时间）；`J_curio.override_ready=1` 当且仅当接管通道心跳正常且备份控制器可用。
- **定义 213（OCB-UX 交互预算老虎机）**：臂 = 交互风格 `{concise, guided, explanatory}` × 自主权 `{confirm, notify, auto}` × LIRO 模式 `{full, fast, degraded}`，聚合为 K=16；奖励 `r_t = progress_t + U_ux,t − κ_c·C_int,t − κ_s·switch_penalty`，其中 `U_ux` 含校准奖励与负荷惩罚。
- **定义 214（J_curio 扩展证书）**：`J_curio = (J_liro, b_hash, dialogue_act, ux_ok, Δτ, explanation_hash, override_ready, interaction_cost)`。`Valid(J_curio) ⇔ Valid(J_liro) ∧ ux_ok ∧ belief_fresh ∧ (未发解释 ∨ F=1) ∧ override_ready ∧ dialogue_act ∈ 𝒜_d^safe`。
- **定义 215（交互安全单调性）**：任意时刻 CURIO 实际可执行动作集 `𝒜_t^CURIO ⊆ 𝒜_t^LIRO_safe`；交互层只能经由 `defer/revoke/warn/confirm` 收缩动作集，不能因用户口头许可、解释或信任提升而扩张 LIRO 的安全集。
- **定义 216（交互遗憾）**：相对「全信息 + 零交互成本」的 clairvoyant 策略，`R_T^int = R_T^LIRO + c_ask·N_ask + c_ux·T + R_T^belief`，其中 `R_T^belief` 为信念误差导致的任务遗憾；CURIO 目标是在 UXC 约束下最小化 `R_T^int`。

## 2. 关键算法骨架（完整伪代码见产物区）

```python
# 语义流（10–100Hz）
b = dstg.update(language, gesture, gaze, P_cloud, ssb, J_liro)   # 安全感知信念
u = uxm.update(interaction_signals)                               # 用户状态
if b.ambiguous() or u.trust_miscalibrated():
    q = vco.select_question(b, u, budget)                         # VOI 澄清

act = dap.select(b, u, J_liro)                                    # 安全约束对话动作
if act == 'execute':
    e = xcert.explain(J_curio, u) if explain_needed(u, b) else None
    alpha = tca.regulate(b, u, J_curio)                           # 信任校准自主权
# 实时流（1–10kHz，零学习写操作）
realtime_step_curio(M, b, act, alpha, J_curio)                    # 仅安全门 + 已认证技能展开
```

## 3. 保证概要与推导要点（完整推导见产物区）

- **引理 5（grounded 指代误差可控）**：若 DST-G 的指代后验校准且只在高 margin 或澄清后执行，则单次执行指代错误概率 `≤ δ_ref + ε_ref`，其中 `ε_ref` 为 grounding 观测误差上界；`m_ref < δ_m` 时 VCO 强制澄清。
- **定理 4（交互安全单调性）**：若 `𝒜_t^CURIO ⊆ 𝒜_t^LIRO_safe` 且每次执行满足 `Valid(J_curio) ⇒ Valid(J_liro)`，则 CURIO 的任何执行继承 LIRO 的几何/技能/干扰安全保证；UX 优化不会降低物理安全。
- **定理 5（VOI 澄清的预算近似最优）**：在 A84（信息增益次模、问题成本均匀）下，预算 `N_max` 的贪心 VOI 澄清达到 `(1−1/e)OPT`；若 `VOI(q) ≤ 0`，单步最优就是不问。
- **定理 6（信任校准收敛）**：在用户状态平稳、观测噪声有界、更新步长满足 Robbins–Monro 条件下，`E[(τ_t − τ*)^2] = O(1/t) + bias²`；TCA 的迟滞与 LCB 约束使过度信任事件概率 `≤ δ_o + δ_conc`。
- **定理 7（交互开销有界）**：若每次被接受的澄清使信念熵至少下降 `δ_info`，则 `E[N_ask] ≤ min(N_max, H(b_0)/δ_info + 1)`；交互时间 `≤ N_max·(T_ask+T_resp)`，且全部发生在语义流，实时路径只增加 `<0.1ms` 的安全门。
- **命题（解释忠实性）**：XCERT 只从 J_curio 字段生成 claim，并由规则验证器过滤无支撑模板，因此 `F(e,J)=1`，结构化解释的「证书幻觉率」为 0。
- **命题（HOC 接管安全）**：若备份控制器 `K_backup ∈ 𝒦_safe` 且接管延迟 `≤ T_override`，则在 A88（安全集前向不变、速度/力有界）下，接管窗口内系统不离开安全集。
- **实时性**：DST-G 更新 <2ms、DAP 决策 <0.1ms、VCO <5ms、UXM <0.1ms、XCERT 模板选择 <10ms、TCA <1ms，均在语义流；实时流增加交互安全门 <0.1ms，总实时路径仍 ≤2.1ms。

## 5. 本轮最大风险

**一句话**：若 UXM 推断的信任与认知负荷与真实用户状态存在系统性偏差（尤其把「过度信任」误判为「已校准」），TCA 会在用户尚未理解证书时授予高自主权，而 XCERT 的自信解释又会放大这种过度信任——交互层将从「安全约束的传导器」变成「信任的洗白器」。

# 第 64 轮产物 · 创新点清单 v4：CURIO（Conversational User-centric Robust Interactive Operations：安全感知对话管理 × 信任校准用户体验 × 人因接管闭环，DST-G×DAP×VCO×UXM×UXC×TCA×XCERT×CSB×HOC×OCB-UX×J_curio）

## 2. 形式化定义（完整版）

**定义 201（CURIO 闭环）** CURIO 是 LIRO 的交互层升级：在「语义流 ∘ 实时流」骨架上挂载 DST-G（安全感知对话状态）、DAP（安全约束对话策略）、VCO（VOI 澄清）、UXM/UXC（用户模型与体验契约）、TCA（信任校准自主权）、XCERT（证书解释）、CSB（对话场景银行）、HOC（人类接管契约）、OCB-UX（交互预算调度），并将 J_liro 扩展为 J_curio。不变式：
1. **交互只收缩安全集**：`∀t, 𝒜_t^CURIO ⊆ 𝒜_t^LIRO_safe`；
2. **学习只在语义流**：DST-G/DAP/VCO/UXM/XCERT/CSB/TCA/OCB-UX 的更新均发生在 10–100Hz 语义流；
3. **实时流零学习写操作**：实时路径仅做「读信念缓存 → 交互安全门 → 已认证技能展开 → 接管检查」，不更新任何模型参数；
4. **证书链**：`Valid(J_curio) ⇒ Valid(J_liro)`，交互层不得单独宣称物理安全。

**定义 202（DST-G 安全感知对话状态）** 对话信念为
`b_t ∈ Δ(𝒢 × ℛ × 𝒞 × 𝒫) × 𝒦`，
其中 `𝒢` 为目标谓词空间，`ℛ` 为指代空间，`𝒞` 为约束空间（时间/力/禁触区/精度），`𝒫` 为权限空间（是否允许高风险动作、是否需要 consent），`𝒦` 为能力状态：
`𝒦 = (valid, ρ_rob, ρ_dir, ℱ_feas, ttl)`，
`valid = Valid(J_liro)`，`ℱ_feas` 为 `𝒫_feas(φ̂, r)` 中当前可执行的技能集，`ttl` 为证书剩余有效期。观测 `o_t = (l_t, gesture_t, gaze_t, P_cloud, SSB_match, J_liro)`；更新规则
`b_{t+1} ∝ Z(o_t, a_t) · T(b_t, a_t)`，
其中 `T` 为目标/指代/约束的转移模型（用户可能改主意、指代漂移、约束追加），`Z` 为观测似然（含 grounding 项）。能力分量 `𝒦` 不是概率信念，而是由 J_liro 与 CSP 确定性推导的**安全事实**；当 `ttl` 过期或 `valid=0` 时，`execute` 动作被硬屏蔽。

**定义 203（Grounded Referent Posterior）** 给定语言 `l_t`、点云 `P_cloud` 与 CSB 场景银行：
`P(r | l_t, P_cloud, SSB) ∝ P(l_t | r) · exp(β·sim(E_txt(l_t), E_geo(obj_r)) + γ·sim(fp_cloud, fp_r) + η·1[r ∈ gaze_cone])`，
其中 `E_txt` 为语言编码器，`E_geo` 复用第 63 轮 LSF 的冻结几何编码器，`fp_r` 为 CSB 中该物体的点云指纹，`gaze_cone` 为注视锥。输出指代后验 `p_r`、决策 margin `m_ref = p_(1) − p_(2)` 与歧义熵 `H_ref = −Σ p_r log p_r`。当 `m_ref < δ_m` 或 `H_ref > H_max` 时标记 `ambiguous=True`，进入 VCO 澄清流程。

**定义 204（DAP 安全约束对话策略）** 对话动作集
`𝒜_d = {confirm(g), clarify(r,q), explain(e), warn(risk), propose(τ), defer(reason), execute(τ), revoke(reason)}`。
策略 `π_d: b_t → Δ(𝒜_d)` 是约束 POMDP 的解：
`max_{π_d} E[Σ_{t=0}^{T} γ^t (U_task(s_t, a_t) + U_ux(u_t, a_t) − λ_c C_int(a_t))]`
s.t.
1. `a_t = execute(τ) ⇒ b_t.𝒦.valid ∧ pre_τ(φ̂,r) ∧ τ ∈ b_t.𝒦.ℱ_feas`；
2. `risk(b_t) > r_warn ⇒ a_t ∈ {warn, defer, revoke}`；
3. `Δτ_t > δ_o ∨ user_asks_explanation ⇒ explain ∈ a_t`（可与 confirm/warn 组合）；
4. `b_t.𝒦.ℱ_feas = ∅ ∨ b_t.𝒦.valid = 0 ⇒ a_t ∈ {warn, defer, revoke}`。
其中 `Shield-D` 是 `execute` 前的最后一道过滤：若 DAP 提案的 `τ` 违反 pre-condition 或 J_liro 失效，则投影到 `defer`，并生成 `warn` 解释；投影距离超过 `δ_skill` 时升级为 `ask_clarify_skill`。DAP 离线用点基值迭代（PBVI）或约束 MCTS 求解；在线仅做动作选择（`<0.1ms`），不学习。

**定义 205（VOI 澄清）** 对候选问题 `q`（如「你指的是左边透明杯还是右边白杯？」），答案空间 `𝒜(q)`，后验 `b^q_a`：
`VOI(q) = E_{a∼Z(q)}[ max_{a'∈𝒜_exec} U(a', b^q_a) ] − max_{a'∈𝒜_exec} U(a', b) − c_ask(q)`，
其中 `𝒜_exec` 为当前安全可执行动作集（含 defer）。仅当 `VOI(q) > 0` 且 `N_ask < N_max` 时发问；若有多个候选问题，按 `VOI(q)/c_ask(q)` 排序。`U` 定义为
`U(a,b) = P_success(b,a)·u_task − λ_risk·risk(b,a) + λ_trust·(−Δτ(b,a)) − λ_load·ℓ(b)`。
若没有正 VOI 问题，DAP 在安全集内选择最优动作，并显式输出「我按当前理解执行，若不对请打断」的低成本 confirm，而不是静默执行高风险动作。

**定义 206（UXM 用户状态）** `u_t = (e_t, ℓ_t, τ_t, p_t) ∈ [0,1]^4`：
- `e_t`：专长（新手/中级/专家），从术语使用、纠正次数、操作速度估计；
- `ℓ_t`：认知负荷，从响应延迟、话语长度、打断频率、重复澄清与 NASA-TLX 短量表估计；
- `τ_t`：信任，从是否检查、是否放手、是否接受建议、显式信任评分估计；
- `p_t`：偏好（简洁/引导/解释型），从交互风格选择与满意度估计。

观测模型 `y_t = h(u_t) + ε_t`，`ε_t` 有界；更新采用卡尔曼/贝叶斯滤波：
`u_{t+1} = u_t + K_t(y_t − h(u_t))`，`K_t = Σ_t H^T(HΣ_tH^T+R)^{-1}`，`Σ_{t+1} = (I−K_tH)Σ_t + Q`。
真实可靠度 `R_t` 由 CSB 中同类场景（`fp_cloud` 近邻 + 技能序列 + 证书等级）的历史成功率给出 conformal 下界：
`R_t = Quantile_α({success_i : i ∈ N_k(scene)})`，其中 `N_k` 为 CSB 的 k 近邻场景。信任校准误差 `Δτ_t = |τ_t − R_t|`；过度信任 `τ_t > R_t + δ_o`，信任不足 `τ_t < R_t − δ_u`。注意：`R_t` 只用于交互决策，不替代 J_liro 的安全判定；安全判定仍由第 63 轮证书给出。

**定义 207（UXC 用户体验契约）** `UXC = (L_max, N_max, E_min, Δτ_max, C_max, T_override)`：
- `L_max`：从用户话语结束到首次可见/可听反馈的感知延迟上限（默认 300ms；高风险确认 ≤500ms）；
- `N_max`：每任务确认/澄清总次数上限（默认 4 次；新手可自适应上调但不超过 6）；
- `E_min`：解释充分性下限（理解测试三项中至少两项通过，`E_suff ≥ E_min`）；
- `Δτ_max`：信任校准误差上限（默认 0.15）；
- `C_max`：认知负荷上限（默认 NASA-TLX 归一化 ≤0.7）；
- `T_override`：接管延迟上限（默认 50ms）。

`π_ux` 可行 ⇔ 上述指标均满足 ∧ `Valid(J_liro)`。UX 优化问题为约束 MDP：
`max_{π_ux} E[U_task + U_ux]` s.t. `π_ux` 可行 ∧ `𝒜^CURIO ⊆ 𝒜^LIRO_safe`。
若可行集为空（例如用户要求跳过所有确认但任务风险过高），则优先满足安全地板，返回 `defer` 并解释冲突，而不是违反安全约束。

**定义 208（TCA 信任校准自主权调节）** 自主权 `α ∈ {0,1,2,3}`：
- `0`：逐步确认（每个技能前 confirm）；
- `1`：关键确认（仅高风险/不可逆技能前 confirm）；
- `2`：通知（执行前告知，不强制确认）；
- `3`：自主（仅在异常或风险超阈值时通知）。

定义可靠度置信下界 `LCB_β(R_t, α) = R_t − β_α·sqrt(log(1/δ)/(2n_t))`，其中 `n_t` 为同类场景样本数，`β_α` 随自主权等级增大。升级规则：
`α_{t+1} = min(3, α_t + 1)` 仅当 `LCB_β(R_t, α_t+1) ≥ R_min(α_t+1)`，`Δτ_t ≤ δ_o`，`Valid(J_curio)`，且连续 `n_up` 次无事故/无纠正；
降级规则：任何事故、用户纠正、`Δτ_t > δ_o`、`ttl` 过期或 `ρ_rob < ρ_min` 立即 `α_{t+1} = max(0, α_t − 1)`。
`R_min(α)` 是自主权等级 α 的最低可靠度要求（例如 `R_min(3)=0.95, R_min(2)=0.9, R_min(1)=0.8, R_min(0)=0`）。迟滞窗口 `n_up` 与降级即时性避免自主权抖动。**关键**：TCA 只影响确认/通知频率与交互成本，不改变 LIRO 的安全证书；即使 `α=3`，`execute` 仍要求 `Valid(J_liro)` 且通过 Shield-D。

**定义 209（XCERT 证书解释）** 解释空间为有限的结构化模板集合 `ℰ_template`，每个模板由若干 claims 组成；claim 的支撑集为 J_curio 字段的子集。`XCERT(J_curio, u_t)` 的生成流程：
1. 从 J_curio 提取可解释事实：`(ρ_rob, ρ_dir, 技能序列, 主要风险源, 证书有效期, 接管方式)`；
2. 根据 `u_t` 选择解释深度：新手 → 低术语、类比、明确接管步骤；专家 → 数值裕度、证书字段、失败模式；
3. 选择模板 `e* = argmax_e E[KL(P(τ|e) || P(τ))] − c_exp(e)`，s.t. `F(e,J)=1`；
4. 规则验证器检查每个 claim 是否被 J_curio 蕴含；未通过则丢弃并回退到最小忠实解释。
忠实性：`F(e,J)=1` 当且仅当 `∀c∈claims(e), ∃s⊆J: c 由 s 蕴含`。**禁止**生成「绝对安全」「绝不会失败」等证书不支持的 claim。

**定义 210（解释充分性）** `E_suff = 1` 当且仅当用户在解释后通过三项理解测试：
1. 能说出当前任务的成功率/可靠度下界（±0.1 容差）；
2. 能说出主要风险源（几何歧义/低摩擦/干扰/技能不可行等）；
3. 能说出何时应接管（例如「当它反复询问同一物体或进入禁触区时」）。
理解测试用简短选择题或复述评估，而不是仅看用户自评分；`E_min` 默认 0.67（三项中至少两项）。

**定义 211（CSB 对话场景银行）** 扩展第 63 轮 SSB：
`scene_sig = (V_sig, T_sig, fp_cloud, φ_sig, dyn_annot, d_sig)`，
`d_sig = (intent_confusion, clarify_history, correction_type, Δτ, ℓ, α)`：
- `intent_confusion`：目标/指代后验熵与 top-2 混淆对；
- `clarify_history`：问题、回答、回答后信念变化；
- `correction_type`：指代纠正、约束追加、目标撤销、权限拒绝；
- `Δτ`：该场景下的信任校准误差；
- `ℓ`：认知负荷；
- `α`：自主权等级。

Mine：当出现「用户纠正、重复澄清、过度信任事件、高负荷、接管」时创建/更新交互场景；优先匹配 `fp_cloud`（几何）与 `d_sig`（交互）。Mut：继承 SSB 的几何变异，并新增交互变异：① 用户话语改写（同义/省略/指代漂移）；② 歧义注入（增加相似物体、遮挡关键特征）；③ 用户类型切换（新手/专家/急躁/低负荷）；④ 解释风格变异（简洁/引导/解释）。簇数封顶 64，Hedge 权重低于 0.01 的簇定期合并/淘汰。

**定义 212（HOC 人类接管契约）** 接管命令 `o_t ∈ {continue, stop, retreat, take_over}`，检测延迟 `τ_o ≤ T_override`。定义备份控制器 `K_backup ∈ 𝒦_safe`（预计算的保守阻抗/制动策略），在接管窗口内实时执行。高风险动作需要显式 consent token `c_t`，token 包含动作摘要、风险等级、过期时间；`consent` 只能**收缩**动作集（允许执行某个已认证动作），不能扩张 LIRO 安全集。`J_curio.override_ready=1` 当且仅当：接管通道心跳正常、`K_backup` 可用、当前状态在 `K_backup` 的吸引域内、consent token 未过期（如需要）。接管优先级高于 DAP/TCA/OCB-UX：一旦检测到接管命令，实时流立即切换到 `K_backup`，语义流后续再解释与学习。

**定义 213（OCB-UX 交互预算老虎机）** 臂空间：
`𝒜_ocb = {(style, autonomy, liro_mode)}`，
`style ∈ {concise, guided, explanatory}`，`autonomy ∈ {confirm, notify, auto}`，`liro_mode ∈ {full, fast, degraded}`，共 18 臂；为保持 EXP3 效率聚合为 K=16（`degraded` 与 `fast` 在低算力时合并，`confirm/notify` 在低风险时合并）。每语义步选择臂 `a_t`，奖励
`r_t = progress_t + U_ux,t − κ_c·C_int,t − κ_s·𝟙[style_t ≠ style_{t−1} ∨ autonomy_t ≠ autonomy_{t−1}]`，
归一化到 `[0,1]`。`U_ux,t` 含信任校准奖励 `−λ_τ|τ_t − R_t|`、负荷惩罚 `−λ_ℓ ℓ_t`、可控性奖励（用户成功打断/接管）。EXP3 重要性加权更新 `w_a ← w_a·exp(η·r̂_t)`；硬安全规则：被选臂必须满足 `Valid(J_curio)` 且不得突破 TCA 允许的最高自主权。

**定义 214（J_curio 扩展证书）** 
`J_curio = (J_liro, b_hash, dialogue_act, ux_ok, Δτ, explanation_hash, override_ready, interaction_cost)`。
验证规则：
`Valid(J_curio) ⇔ Valid(J_liro) ∧ ux_ok ∧ belief_fresh ∧ (未发解释 ∨ F=1) ∧ override_ready ∧ dialogue_act ∈ 𝒜_d^safe`。
其中 `belief_fresh` 要求 `b_t` 的时间戳与当前观测差 ≤ `Δ_belief`；`ux_ok` 要求 UXC 六项指标均满足；`dialogue_act ∈ 𝒜_d^safe` 要求动作满足定义 204 的四条硬约束。审计链：`b_hash` 追溯对话信念版本，`explanation_hash` 追溯解释模板与证书字段，`interaction_cost` 记录本轮交互开销。`Valid(J_curio)` 是 `execute` 的必要条件；`warn/defer/revoke` 不需要 `ux_ok`，但需要 `Valid(J_liro)` 或明确的失效原因。

**定义 215（交互安全单调性）** 对任意时刻 t，CURIO 的实际可执行动作集
`𝒜_t^CURIO = {a ∈ 𝒜_t^LIRO_safe : DAP 允许 a ∧ Shield-D 通过 a ∧ HOC 未撤销 a ∧ TCA 不禁止 a}`，
因此 `𝒜_t^CURIO ⊆ 𝒜_t^LIRO_safe`。交互层通过 `defer/revoke/warn/confirm` 收缩动作集；用户口头许可、解释、信任提升、自主权升级都**不能**把 LIRO 安全集之外的动作加入 `𝒜_t^CURIO`。这是 CURIO 的核心安全不变式。

**定义 216（交互遗憾）** 相对「全信息 + 零交互成本」的 clairvoyant 策略 `π*`：
`R_T^int = R_T^LIRO + c_ask·N_ask + c_ux·T + R_T^belief`，
其中 `R_T^LIRO` 为第 63 轮遗憾，`N_ask` 为澄清次数，`c_ux·T` 为交互延迟/负荷成本，`R_T^belief` 为信念误差导致的任务遗憾（例如指代错误、约束遗漏）。CURIO 在 UXC 约束下最小化 `R_T^int`，其权衡是：更多澄清降低 `R_T^belief` 但增加 `c_ask·N_ask`；更高自主权降低交互成本但可能增加误执行风险（由 J_curio 安全门兜底）。

```python
class GroundedDialogueStateTracker:
    """b(goal, referent, constraint, permission) × 𝒦(J_liro)。语义流更新。"""
    def __init__(self, d_txt=256, d_geo=128, d_state=128, delta_m=0.15):
        self.E_txt = TextEncoder(d_txt)
        self.E_geo = FrozenGeometryEncoder(d_geo)      # 复用 LSF 的 E_geo
        self.transition = GoalTransitionModel(d_state)
        self.obs_model = ObservationModel(d_state)
        self.delta_m = delta_m

    def ground_referent(self, l_t, P_cloud, ssb, gaze):
        cands = ssb.candidate_objects(P_cloud)          # 几何候选
        logits = []
        for obj in cands:
            s_txt = cosine(self.E_txt(l_t), self.E_txt(obj.label))
            s_geo = cosine(self.E_geo(P_cloud), obj.geo_emb)
            s_fp = cosine(cloud_fp(P_cloud), obj.fp_cloud)
            s_gaze = 1.0 if obj.in_cone(gaze) else 0.0
            logits.append(BETA*s_txt + GAMMA*s_geo + ETA*s_fp + ZETA*s_gaze)
        p = softmax(torch.tensor(logits))
        order = torch.argsort(p, descending=True)
        m_ref = (p[order[0]] - p[order[1]]).item() if len(p) > 1 else 1.0
        H_ref = -(p * torch.log(p + 1e-9)).sum().item()
        return {cands[i]: p[i].item() for i in range(len(cands))}, m_ref, H_ref

    def update(self, l_t, gesture, gaze, P_cloud, ssb, J_liro):
        ref_post, m_ref, H_ref = self.ground_referent(l_t, P_cloud, ssb, gaze)
        K = CapabilityState(valid=J_liro.valid, rho_rob=J_liro.rho_rob,
                            rho_dir=J_liro.rho_dir, feasible=J_liro.feasible_skills,
                            ttl=J_liro.ttl)
        # 目标/约束/权限的贝叶斯更新（语言 + 手势 + 上下文）
        b = self.obs_model.update(self.prev_b, l_t, gesture, ref_post)
        b.capability = K
        b.ambiguous = (m_ref < self.delta_m) or (H_ref > H_MAX)
        b.timestamp = now()
        self.prev_b = b
        return b

class CapabilityState:
    def __init__(self, valid, rho_rob, rho_dir, feasible, ttl):
        self.valid, self.rho_rob, self.rho_dir = valid, rho_rob, rho_dir
        self.feasible, self.ttl = feasible, ttl
```

```python
class DialogueActPolicy:
    """约束 POMDP 的在线动作选择；离线 PBVI/约束 MCTS 求解。"""
    def __init__(self, action_set, policy_net, r_warn=0.3):
        self.A = action_set
        self.policy = policy_net
        self.r_warn = r_warn

    def select(self, b, u, J_liro):
        # 1) 安全硬屏蔽：构造可行对话动作集
        feasible = []
        for a in self.A:
            if a.kind == 'execute':
                if not (b.capability.valid and b.capability.feasible and J_liro.valid):
                    continue
                if b.ambiguous and risk(b) > self.r_warn:
                    continue                         # 歧义 + 高风险：不能静默执行
            if risk(b) > self.r_warn and a.kind not in ('warn', 'defer', 'revoke'):
                continue
            if (u.trust_miscalibrated() or b.user_asked_explain) and a.kind not in ('explain', 'confirm', 'warn'):
                continue
            feasible.append(a)
        if not feasible:
            return DialogueAct('defer', reason='no_safe_action')
        # 2) 约束 POMDP 策略打分（只在可行集内）
        scores = self.policy.score(b, u, feasible)
        return feasible[argmax(scores)]

class VOCPlanner:
    """VOI(q) = E_a[max_a' U(a', b^q_a)] - max_a' U(a', b) - c_ask(q)。"""
    def __init__(self, max_asks=4, min_voi=0.02):
        self.max_asks, self.min_voi = max_asks, min_voi

    def select_question(self, b, u, budget):
        if budget <= 0 or not b.ambiguous:
            return None
        best_q, best_voi = None, -float('inf')
        base = max_action_utility(b, u)
        for q in self.generate_candidate_questions(b):
            exp_util, entropy_after = 0.0, 0.0
            for ans, p_ans in q.answer_distribution(b):
                b_q = bayes_update(b, q, ans)
                exp_util += p_ans * max_action_utility(b_q, u)
                entropy_after += p_ans * entropy(b_q)
            voi = exp_util - base - q.cost(u)          # c_ask 含负荷/延迟
            ratio = voi / max(q.cost(u), 1e-6)
            if voi > self.min_voi and ratio > best_voi:
                best_q, best_voi = q, ratio
        return best_q
```

```python
class UserExperienceModel:
    """u=(expertise, load, trust, preference)。卡尔曼/贝叶斯在线更新。"""
    def __init__(self):
        self.u = np.array([0.5, 0.3, 0.5, 0.5])       # 先验
        self.Sigma = np.eye(4) * 0.25

    def update(self, y):
        H = observation_jacobian(self.u)
        R = np.diag([0.05, 0.05, 0.05, 0.1])
        K = self.Sigma @ H.T @ np.linalg.inv(H @ self.Sigma @ H.T + R)
        self.u = self.u + K @ (y - h(self.u))
        self.Sigma = (np.eye(4) - K @ H) @ self.Sigma + np.diag([0.01]*4)
        return UserState(*np.clip(self.u, 0, 1))

    def trust_miscalibrated(self, R_t, delta_o=0.15, delta_u=0.15):
        tau = self.u[2]
        return (tau > R_t + delta_o) or (tau < R_t - delta_u)

class UXContract:
    def __init__(self, L_max=0.3, N_max=4, E_min=0.67, dtau_max=0.15,
                 C_max=0.7, T_override=0.05):

class TrustCalibratedAutonomy:
    """α ∈ {0,1,2,3}；LCB 约束 + 迟滞；只影响交互，不改安全集。"""
    def __init__(self, beta=(0.0, 0.1, 0.2, 0.3), R_min=(0.0, 0.8, 0.9, 0.95),
                 n_up=5):
        self.beta, self.R_min, self.n_up = beta, R_min, n_up
        self.alpha, self.success_streak = 0, 0

    def lcb(self, R, n, alpha):
        return R - self.beta[alpha] * np.sqrt(np.log(1/0.05) / (2*max(n, 1)))

    def regulate(self, R_t, n_t, u, J_curio, incident=False, corrected=False):
        if incident or corrected or abs(u.trust - R_t) > 0.15 or not J_curio.valid:
            self.alpha = max(0, self.alpha - 1)
            self.success_streak = 0
            return self.alpha
        self.success_streak += 1
        if self.success_streak >= self.n_up and self.alpha < 3:
            nxt = self.alpha + 1
            if self.lcb(R_t, n_t, nxt) >= self.R_min[nxt] and abs(u.trust - R_t) <= 0.15:
                self.alpha, self.success_streak = nxt, 0
        return self.alpha
```

```python
class CertificateExplainer:
```

### IP-212 OCB-UX（交互预算老虎机）

```python
class InteractionBudgetBandit:
    ARMS = [(style, autonomy, liro) for style in ('concise', 'guided', 'explanatory')
                                  for autonomy in ('confirm', 'notify', 'auto')
                                  for liro in ('full', 'fast')]       # 18 -> K=16 聚合
    def __init__(self, K=16, eta=0.3, kappa_c=0.2, kappa_s=0.1):
        self.w = np.ones(K) / K
        self.eta, self.K = eta, K
        self.kappa_c, self.kappa_s = kappa_c, kappa_s
        self.prev_style, self.prev_autonomy = None, None

    def choose(self, J_curio, tca_alpha):
        feasible = [i for i, a in enumerate(self.ARMS)
                    if J_curio.valid and autonomy_index(a[1]) <= tca_alpha]
        p = self.w[feasible] / self.w[feasible].sum()
        idx = np.random.choice(feasible, p=p)
        return idx, self.ARMS[idx]

    def update(self, idx, progress, ux_utility, cost, style, autonomy):
        switch = 1.0 if (style != self.prev_style or autonomy != self.prev_autonomy) else 0.0
        reward = np.clip(progress + ux_utility - self.kappa_c*cost - self.kappa_s*switch, 0, 1)
        r_hat = reward / max(self.w[idx], 1e-6) / self.K
        self.w[idx] *= np.exp(self.eta * r_hat / self.K)
        self.w /= self.w.sum()
        self.prev_style, self.prev_autonomy = style, autonomy
```

```python
def CURIO_round(M, obs, user_input):

        u = M.uxm.update(user_input.response_signals)

                    cost=interaction_cost(q, act), style=M.arm.style,

def realtime_step_curio(M, act, alpha, tau, theta_bind, x_prime, goal, J_curio):
    # ———— 实时流（1–10kHz）：零学习写操作 ————
    cmd, t_cmd = M.hoc.poll()
    if cmd != 'continue':
        K_cmd = M.hoc.preempt(M.state, cmd)
        M.ertc.dispatch(K_cmd)
        return M.hoc.K_backup(M.state), build_override_evidence(cmd), None, True

    if act.kind != 'execute':
        M.ertc.dispatch(safe_hold(M.state))           # warn/defer/revoke：安全保持
        return safe_hold(M.state), build_wait_evidence(act), None, False

    # 交互安全门：证书 + 信念 + 接管就绪
    if not (J_curio.valid and M.hoc.ready(M.state)):
        M.ertc.dispatch(safe_hold(M.state))
        return safe_hold(M.state), build_block_evidence(J_curio), None, False

    first_skill, first_theta = tau[0], theta_bind[0]
    K_seq = first_skill(x_prime, first_theta)
    K_safe, rho_rob, _, geo_conflict = wcv_geo_compile(
        M.olp_geo, x_prime, M.eeis, M.anchor.phi_hat, M.rsc.r,
        M.lsf.g_cache, M.lsf)
    cert_exec = M.ertc.dispatch(K_seq[0])
    EV_exec = wait_contact_and_build_evidence()
    M.usr.push_evidence(EV_exec)
    return K_safe, EV_exec, cert_exec, False
```

## 4. 推导

**引理 5（grounded 指代误差可控）** 设 DST-G 的指代后验校准，且执行规则为「仅在 `m_ref ≥ δ_m` 或澄清后执行」。若 grounding 观测误差上界为 `ε_ref`，则单次执行指代错误概率 `≤ δ_ref + ε_ref`，其中 `δ_ref` 为 margin 不足导致的误判概率。证明：若 `m_ref ≥ δ_m`，由后验校准性，错误概率 ≤ `1 − p_(1) ≤ δ_m`；若经过澄清，错误概率 ≤ `ε_ref`（澄清答案作为高精度观测）。VCO 在 `m_ref < δ_m` 时强制澄清，故未澄清路径的错误概率被 `δ_m` 控制。取 `δ_ref = δ_m`。∎

**定理 4（交互安全单调性）** 由定义 215，`𝒜_t^CURIO ⊆ 𝒜_t^LIRO_safe`。第 63 轮已证 `Valid(J_liro) ⇒ 执行动作满足几何/技能/干扰安全约束`。CURIO 的 `execute` 额外要求 `Valid(J_curio)`，而 `Valid(J_curio) ⇒ Valid(J_liro)`（定义 214）。因此任何 CURIO 执行的物理动作仍在 LIRO 安全集内；UX 优化、解释、信任提升、自主权升级均只改变交互层，不改变 `𝒜_t^LIRO_safe`。由归纳，整个轨迹安全。∎

**定理 5（VOI 澄清的预算近似最优）** 设候选问题集合 `Q`，预算 `N_max`，目标函数 `F(S) = E[max_a U(a, b_S)] − max_a U(a, b_∅)` 为单调次模（A84），问题成本均匀。则贪心 VOI 选择达到 `(1−1/e)OPT`；若 `VOI(q) ≤ 0`，由一步最优性，不发问是最优动作（在单步决策意义下）。证明：次模单调函数在基数约束下的贪心近似为 `(1−1/e)`（Nemhauser–Wolsey–Fisher）；`VOI(q)>0` 等价于 `F(S∪{q})−F(S) > c_ask`，故贪心即最大化边际收益/成本。∎

**定理 6（信任校准收敛）** 设用户真实信任 `τ*` 平稳，观测 `y_t = τ* + ε_t`，`E[ε_t]=0`，`Var(ε_t) ≤ σ²`，更新为 Robbins–Monro 型 `τ_{t+1} = τ_t + η_t(y_t − τ_t)`，`Ση_t=∞, Ση_t²<∞`。则 `τ_t → τ*` a.s.，且 `E[(τ_t−τ*)^2] = O(η_t) + bias²`。取 `η_t=1/t` 得 `O(1/t)`。TCA 的 LCB 约束与迟滞使自主权升级仅在 `LCB_β(R_t,α) ≥ R_min(α)` 且 `Δτ_t ≤ δ_o` 时发生；在 `R_t` 的 conformal 覆盖假设下，过度信任事件概率 `≤ δ_o + δ_conc`（`δ_conc` 为 conformal 失效概率）。∎

**定理 7（交互开销有界）** 设每次被接受的澄清使信念熵至少下降 `δ_info`，初始熵 `H(b_0)`。则被接受的澄清次数 `N_ask ≤ H(b_0)/δ_info`（熵非负），结合预算得 `E[N_ask] ≤ min(N_max, H(b_0)/δ_info + 1)`。交互时间 ≤ `N_max·(T_ask+T_resp)`；由于 DST-G/DAP/VCO/UXM/XCERT 均在语义流，实时路径只增加交互安全门（读缓存 + 布尔检查）`<0.1ms`，不影响 1–10kHz 控制周期。∎

**命题（解释忠实性）** XCERT 的 claim 生成受限于 `extract_certificate_facts(J_curio)`，验证器 `claim_supported_by` 只接受由 J_curio 字段蕴含的 claim；无支撑模板被丢弃。因此输出解释满足 `F(e,J)=1`，结构化解释的「证书幻觉率」为 0。自然语言的润色可能引入歧义，但不引入新事实；若验证器不可判定，则回退到最小忠实模板。∎

**命题（HOC 接管安全）** 设备份控制器 `K_backup ∈ 𝒦_safe`，`𝒦_safe` 对 `K_backup` 前向不变，且接管检测延迟 `≤ T_override`。在 A88（速度/力有界、状态估计误差有界）下，接管窗口内系统状态始终在 `𝒦_safe` 内；若 `K_backup` 不可用则紧急制动 `emergency_brake`，其制动距离在安全包络内。因此接管过程中不发生不安全接触。∎

**命题（UX 契约与安全地板相容）** 若 UXC 可行集非空，则存在满足契约的 `π_ux`；若可行集为空，CURIO 返回 `defer` 并解释冲突，而不是放松 `Valid(J_liro)`。由定理 4，放松 UX 约束不会扩张安全集，故 UX 层无法单独导致物理不安全。∎

## 7. 已知风险

**一句话**：若 UXM 推断的信任与认知负荷与真实用户状态存在系统性偏差（尤其把「过度信任」误判为「已校准」），TCA 会在用户尚未理解证书时授予高自主权，而 XCERT 的自信解释又会放大这种过度信任——交互层将从「安全约束的传导器」变成「信任的洗白器」。

**次级风险与缓解**：
1. **指代 grounding 在透明/镜面/遮挡物体上失效**：DST-G 的几何相似度被镜面反射欺骗 → 提高 `m_ref` 阈值、强制澄清、并把「镜面/透明」加入 CSB 交互变异；必要时降级到纯语言 + 用户确认。
2. **VOI 模型不准导致过度提问或该问不问**：`U` 与 `c_ask` 估计偏差 → 用 CSB 历史离线校准 VOI；设置 `N_max` 硬预算与「高风险必问」规则；对 `m_ref` 极低的情况绕过 VOI 直接澄清。
3. **UXM 信任估计受用户策略性行为影响**：用户可能故意表现出信任以换取速度 → 不把用户自评作为唯一证据；用行为指标（是否检查、是否接管）与最终结果做交叉验证；对高风险动作强制 consent，不依赖信任估计。
4. **解释过度简化导致误解**：XCERT 为降低负荷省略关键风险 → 解释模板设置「必须包含主要风险与接管时机」的最小充分集；`E_suff` 用理解测试而非自评；用户可请求更详细解释。
5. **接管通道延迟/失效**：无线延迟、硬件故障 → 心跳监测 + `override_ready` 门控；`override_ready=0` 时禁止高风险自主执行，退回 `defer` 或低速安全模式。
6. **CSB 交互场景过拟合特定用户**：场景银行被少数受试者主导 → 按用户类型分层、设置每类簇上限、定期淘汰低权重簇；跨用户验证。
7. **对话策略与安全策略冲突**：为保持流畅而跳过确认 → 定义 204 的硬约束与定义 215 的单调性在代码层强制；任何跳过确认的请求只能降低自主权，不能绕过 `Valid(J_curio)`。
8. **隐私与数据合规**：对话、注视、信任数据敏感 → 本地化存储、脱敏、最小化采集；人因实验数据匿名化并获知情同意。
