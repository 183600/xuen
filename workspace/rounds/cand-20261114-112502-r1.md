# 第 74 轮（承接第 73 轮「MODGAUGE-RAS 计量契约代数」IP-295~301；灵感循环第 1 轮；本轮灵感：「需求洞察」×「意图理解」）

> R73 把证据不确定度变成可组合、可否决、可审计、可热替换的契约，完成了「系统是否知道自己看到了什么、碰到了什么」的计量化。但 R73 仍把一个最关键的量留在审计边界之外：**系统要服务的需求本身**。归纳为三个结构性缺口：
> - **目标外生问题**：R72 的 IRL 推断意图 z，R73 给 z 配了契约，但 z 的先验、z 到实际收益的映射、以及「人到底要什么」始终是外生给定。系统可以持有一张**每一步都合规**的组合证书，却在为一个从未被审计过的目标服务。世界证据的校准，不等于目标的校准。
> - **意图扁平问题**：现有 IRL 把意图当作 |Z|≤8 的分类隐变量，把「请求」「意图」「需求」「反思认可」压成同一层。它无法表达：同一句话在不同语用下是请求/警告/讽刺；「把那个拿过来」的指称、范围、粒度、权衡偏好各自缺失；多个利益相关者的需求冲突；需求随交互漂移。**意图不是标签，是对一个更深层需求的上下文投影。**
> - **测量反作用问题（第五反作用层 L5）**：R73 的反作用通道 χ_R 只允许动作改变**噪声**，默认被测目标不变。但需求不是深度图：问一句「您更在意速度还是安全？」会**改变**人的偏好（偏好建构、锚定、反应效应）；展示一个方案会让人发现原先没说出的约束。观测行为本身进入被观测系统。若把这种干预误当成被动测量，系统会**制造**一个需求，再为它出具「经同意」的证书。
>
> 本轮两个灵感正好补两块：
> - **需求洞察** → **NIM（Need & Intent Metrology）**：把需求重写为**带证据、带预算、带有效域、带反作用通道的隐变量**；六分量（指称/范围/语用/偏好/反思/漂移）+ 需求条件似然 + 有效域 D_need；需求不是奖励函数，而是**可计量、可追溯、会过期**的证据对象。
> - **意图理解** → **三层结构与对齐深度**：请求 r → 意图 z → 需求 ν → 反思认可 L3；意图由逆规划/贝叶斯心智理论推断，而非分类；任何动作必须携带「需求溯源链」，并接受**代理缺口**审计。
>
> 核心命题：**不再只问「证据是否校准」，而问「目标本身是否有证据、能否组合、会不会被测量行为改写、以及在不确定时系统是否只做可逆与可同意的事？」** 把 MODGAUGE 的计量契约代数上推一层，得到 **NEEDGAUGE-RAS**（Need-Evidence Elicitation & Deliberation with GAUGE audits for RAS）——**需求证据计量与可逆许可代数**。

## 0. 直觉与动机

**灵感 1（需求洞察 → 需求是「被证据支撑的隐变量」，不是奖励函数）**
直觉：人类说出的从来不是需求，而是**需求的压缩、延迟与策略性表达**。「帮我订个餐厅」的真实需求可能是「今晚别让我做决定」；「把这个箱子搬上去」的真实需求可能是「别弄坏里面的东西」。产品研究里把这种差距叫 stated / revealed / latent need 的鸿沟；在机器人这里，它直接决定动作后果。因此正确的抽象不是「给 reward 加一项」，而是把需求看成概率模型里的隐变量 ν：可观测的是请求 r 与反馈 φ（接受/拒绝/纠正/示范），不可观测的是 ν；二者之间隔着人的**报告策略** π_R 与**选择策略** π_C。需求不确定度不是一个标量，而是**六类不同认识论机制**的预算：
- **u_ref（指称）**：指的是哪个物体/动作/地点（「那个」歧义）；
- **u_scope（范围/粒度/时域）**：做多少、做多细、做多久（完成 vs 推进；一次性 vs 长期偏好）；
- **u_pragma（语用）**：这句话在做什么（请求/询问/警告/讽刺/客套），以及言外之意；
- **u_pref（偏好/权衡）**：速度-安全-成本-隐私之间的权重与硬约束；
- **u_endorse（反思认可）**：推断出的需求在反思后是否仍被本人认可；这是第二阶需求，也是「人自己还没想清楚」的部分；
- **u_drift（非平稳/多主体）**：需求随交互演化，或不同利益相关者冲突。
与深度六分量同构但更危险：物理噪声可被外部基准校准，需求没有 oracle；唯一可用的「真值」是人的**反思性认可**与**行为一致性**，而两者都可能被系统自身影响。

**灵感 2（意图理解 → 意图是需求在上下文中的投影，对齐有深度）**
直觉：意图理解不是「把句子分类到 8 个槽位」，而是**逆规划（inverse planning）**：假设人是一个带噪声的近似理性规划者，其行为由需求 ν 与上下文 c 决定，那么观察到的请求与选择就给出 ν 的似然。定义投影 π: N × C → Z，意图 z = π(ν, c) 是需求在当前任务粒度上的可见切面。由此得到**对齐深度**：
- **L0 指令对齐**：动作匹配请求的表面内容；
- **L1 意图对齐**：动作实现推断出的目标 z；
- **L2 需求对齐**：动作服务于被证据支持的 ν（包括未说出的约束）；
- **L3 反思对齐**：人在获得反事实信息/解释后，仍认可「这个需求 + 这个动作」。
L0–L2 都可以被行为指标「证明」，L3 不能——这正是论文需要正面处理的**不可识别性**。一个系统可以在 L0/L1 拿满分，同时 L2/L3 完全错误，此即**代理缺口（proxy gap）**。需求洞察的任务，是把 L2/L3 从口号变成可审计、可证伪的测量。

**灵感 3（L5 需求反作用 → 观测会改变被测对象，必须区分测量与干预）**
直觉：深度相机的视角反作用（L4）是「换个角度，噪声变小」；需求 elicitation 是「问一句话，目标可能改变」。二者形式同构、语义相反：
- **测量模式** e ∈ E_obs：询问/观察不改变 ν，只降低 u_need（如非引导性的开放问题、被动记录选择）；
- **干预模式** e ∈ E_int：展示、默认值、框架、社交压力会改变 ν 的分布（锚定、偏好建构、反应效应）。
系统必须为每个 elicitation 动作声明**二象性**：它对噪声做什么（Δu），它对目标做什么（mutation kernel M_e），以及它消耗多少人的注意力/信任（κ_e）。**非操纵不变量**：只允许 E_obs 与 E_soc（苏格拉底式：提升反思清晰度、保持偏好排序不变的干预）；禁止「降低反思质量却提高系统偏好动作概率」的干预。把「操纵」从伦理形容词变成可审计的算子性质，是本轮最重要的形式化点。

**灵感 4（需求组合 → 需求也能串/并/否决，但同意不可补偿）**
直觉：需求天然是组合对象：任务分解是串联；多模态证据（语言 + 示范 + 生理/行为 + 第三方转述）是并联；安全/法律/隐私/拒绝是**非补偿性否决**；多利益相关者是**公平聚合**。R73 的 CCA 可以推广为 NCA，但必须加两条需求侧公理：
- **共享信息不可当独立证据**：同一段对话同时支撑指称与语用，两个分量不能按独立来源缩窄；并联缩窄前要做**共享信息审计**（有效样本量/共同操纵通道）。
- **同意不可平均**：多主体聚合不能用加权平均吞掉少数者的否决权；权利类约束走 VETO，偏好类走 leximin/Nash 公平聚合。
再叠加**决策充分性**：需求不确定度不需要被最小化，只需要降到当前动作不可逆程度所要求的阈值以下。少问、问对、只在必要时问——这既是效率，也是隐私与尊严。

**灵感 5（认证与主张 → 需求证书会过期，陈旧需求是新的失效模式）**
直觉：R73 的模块证书是静态的；需求证书必须带**有效期**。人的需求会变（疲劳、新信息、交互本身），昨天的同意不能授权今天的不可逆动作。因此定义需求证书 J_NEED 的 TTL 与漂移检测；过期/漂移即 need-stub：只允许询问、可逆动作或移交。论文侧继续蒸馏纪律，扩为五条可证伪主张：新增 **C4（需求-意图六分量计量优于通用不确定性）** 与 **C5（反思对齐可被诱发与审计；纯行为对齐可证伪地不足，定理 33）**。不服务主张的组件仍是工程附件。

## 1. 形式化定义（增量：定义 383–400）

**定义 383（NEEDGAUGE-RAS 总览）** NEEDGAUGE-RAS = (MODGAUGE-RAS†, NIM, NC, NCA, χ_E, VONI, RGL, J_NEED, CPB†)。七不变式：
(i) **需求证据完整性**：任何进入许可计算的需求主张必须携带 NC 契约与需求溯源链 τ_need，缺一不得授权；
(ii) **组合单调性**：需求组合经 NCA 校验，观测/苏格拉底模式下不确定度不得「凭空变好」（引理 39）；
(iii) **反作用与二象性完备**：每个 elicitation 通道显式声明 (Δu, M_e, κ_e)；测量与干预必须可区分；
(iv) **非操纵**：仅 E_obs ∪ E_soc 可入许可路径；E_manip 一经检出即否决并记入同意账本（定义 389）；
(v) **同意/可争辩非补偿**：人的拒绝、撤回与质疑是否决票，不得被任何收益抵消（定义 399）；
(vi) **主张绑定**：每个组件 ∈ {C1…C5, 工程附件}，附件不进核心认证路径、不进正文（定义 400）；
(vii) **严格退化链扩展**：需求失效 ⇒ need-stub（定义 396）⇒ 只做可逆/询问/移交；世界侧模块性质不变（定理 32）。

**定义 384（需求-意图-请求三层结构与对齐深度）** 设需求空间 N（结构化：目标 × 约束 × 偏好 × 时域）、意图空间 Z（上下文中的计划/目标）、请求空间 R、反馈空间 Φ、上下文 C、交互史 H。投影 π: N × C → Z。生成模型：
π_R(r | z, ν, c; θ_R), π_C(φ | z, ν, c; θ_C), z = π(ν, c)。
需求后验 b_t(ν) ∝ b_0(ν) · Π_t p(r_t | z_t, ν, c_t) · p(φ_t | z_t, ν, c_t)。**对齐深度** L0–L3 如上；**代理缺口** PG = E_{ν∼b_t}[U(ν, a) − U(ν̂, a)]，其中 ν̂ 是系统实际优化的目标代理。L0/L1 通过不蕴含 L2/L3 通过（定理 33）。

**定义 385（需求-意图计量 NIM）** 六分量：
u_need² = u_ref² + u_scope² + u_pragma² + u_pref² + u_endorse² + u_drift²。
- u_ref：指称落地（实体/动作/位置绑定）的后验熵与校准误差；
- u_scope：HTN/任务语法覆盖后的范围-粒度-时域残差；
- u_pragma：言语行为与言外之意的条件熵（含反事实「若换一种说法」稳定性）；
- u_pref：逆规划/成对比较下效用参数与硬约束的后验宽度；
- u_endorse：反思协议下的第二阶稳定性（重测信度、反事实认可翻转率）；
- u_drift：变化点检测的未解释漂移 + 多主体分歧。
每个分量有独立估计器、独立追溯链 τ_i 与独立密封校准集 SEAL-Need-i；分量合成前做**共享信息审计**（定义 390 PAR）。

**定义 386（需求证据契约 NC）** NC = (T_r, T_ν, 𝒰_in, 𝒰_out, χ_E, D_need, τ_merge, I⊥, TTL, consent_ref, contest_addr, W, seal_ref)。它是 R73 EC 的需求侧特化：新增 **χ_E**（启发通道）、**TTL**（有效期）、**consent_ref**（同意账本引用）、**contest_addr**（可争辩入口）。Module_need = (NC, impl, cert_need)。

**定义 387（需求有效域 D_need）** D_need = {人可合作 ∧ 语言/任务在分布内 ∧ 系统能力覆盖 ∧ 有基本交互带宽 ∧ 反思协议可用 ∧ 无强制/威胁 ∧ 无活跃否决}。D_need 外 ⇒ 需求证据不可用于授权（u_need := ∞），只能进入 need-stub。**D_need 是硬边界，不是软惩罚。**

**定义 388（启发通道 χ_E 与测量-干预二象性）** χ_E: E × N → (Δ(N) × Θ_noise × D_need′ × ℝ_+)：
e ↦ (M_e, Δu_e, D_e, κ_e)，其中 M_e 是作用于需求分布的**干预核**，Δu_e 是期望不确定度下降，κ_e 是人类注意力/信任成本。若 M_e = id，则 e ∈ E_obs（测量）；若 M_e ≠ id，则 e ∈ E_int（干预）。**目标会动**：b_{t+1}(ν) = ∫ M_e(ν | ν′) b_t(ν′) dν′（干预模式下先验被改写，而非仅做似然更新）。这使需求组合单调性只在 E_obs ∪ E_soc 上成立（引理 39）。

**定义 389（非操纵不变量与苏格拉底通道 E_soc）** 对动作 a 与需求 ν，记系统偏好序 ≻_S。e 是**操纵**，若 (a) 它改变人的偏好排序（∃ν, ν′: ν ≻_H ν′ 但 M_e 后 ν′ ≻_H ν），且 (b) 未提升反思认可（Δu_endorse ≥ 0 或认可翻转率不降），且 (c) 提升系统偏好动作的概率。**E_soc** = {e: M_e 保持 ν 的排序（rank-preserving）∧ E[Δu_endorse] ≤ 0（提升反思清晰度）∧ 无隐藏默认值/框架/社交压力}。许可路径只允许 E_obs ∪ E_soc；E_manip 触发 I⊥ 的非补偿否决，并向同意账本写入事件。

**定义 390（需求组合代数 NCA）** 四算子：
- **SER（需求细化）**：u_out ≥ u_A + L_B·u_A；D_out = D_A ∩ D_B；τ_out = τ_merge；I⊥,out = I⊥,A ∪ I⊥,B；χ_E,out = χ_E,B ∘ χ_E,A。
- **PAR（多源证据融合）**：先做**跨源一致性审计**与**共享信息审计**（有效独立样本 m_eff ≥ m_min，共同操纵通道为空）；通过才允许按相关性 ρ̂ 缩窄；失败 ⇒ u_out = max(u_A, u_B)，并置 PAR_AUDIT_FAIL。
- **VETO（硬约束/拒绝）**：validity = validity_A ∧ validity_B；任一否决即整体否决（非补偿，继承 R71/E356 单源不定案）。
- **AGG（多主体公平聚合）**：权利/安全约束走 VETO；偏好类用 leximin（最大化最差者）或 Nash 福利，禁止用加权平均吞掉少数者否决。
- **REVISE（漂移修正）**：变化点后重置后验与 TTL，**不改写历史溯源**（append-only provenance）；修正可降低未来不确定度，但不得追认过去动作。

**定义 391（多主体公平聚合 AGG-FAIR）** 利益相关者集合 S，每个 j 有需求 ν_j 与权利集 β_j。可行动作集 A_feas = {a: ∀j, a 不违反 β_j 的否决}；在 A_feas 上最大化 leximin 或 Nash 社会福利。**同意不进入福利函数**：未同意本身就是不可行，而不是低效用。

**定义 392（VONI 与决策充分性）** 需求信息的价值：
VONI(e) = E[Δ U_decision-relevant | e] / (κ_e + ρ·trust_cost(e))。
**决策充分性**：给定动作 a 的不可逆等级 ℓ(a)，只要求 u_need(ν 中与 a 相关部分) ≤ τ_suff(ℓ(a))，不要求最小化 u_need。提问策略在注意力预算 B_attn 与 E_obs ∪ E_soc 约束下最大化 VONI，达到充分即停（引理 40）。

**定义 393（可逆性门控许可 RGL）** 不可逆等级 ℓ(a) ∈ {0 可逆, 1 有代价可逆, 2 不可逆}，阈值 τ_0 > τ_1 > τ_2。动作 a 被许可当且仅当：
[ℓ(a)=0 ∧ u_need ≤ τ_0] ∨ [ℓ(a)=1 ∧ (u_need ≤ τ_1 ∨ 显式确认)] ∨ [ℓ(a)=2 ∧ u_need ≤ τ_2 ∧ 显式同意 ∧ 对齐深度 ≥ L2 ∧ 无活跃否决]。
不确定时优先选择「既推进任务又降低 u_need」的**可逆探测动作**（epistemic reversible action）。

**定义 394（需求漂移与证书 TTL）** 需求证书带有效期 TTL。漂移检测统计量 D_t = 变化点后验 + 认可翻转率 + 多主体分歧熵；D_t > δ ⇒ 证书提前失效。失效 ⇒ need-stub；重新询问后重签。**陈旧需求不得授权新的不可逆动作**。

**定义 395（需求威胁面 AIC-NEED）** ℰ_need = {提示注入/指令劫持、谄媚与偏好投毒、利益相关者俘获、代理指标 Goodhart、过度询问/监视、操纵性框架、虚假需求/欺骗}。防线：多源一致性 + 共享信息审计、单源不定案、同意账本、非操纵审计、可争辩否决、溯源签名。

**定义 396（need-stub 语义）** stub_need 输出：需求后验 = 均匀（或固定保守先验）、u_need = ∞、D_need = ∅、I⊥ = 一切依赖需求的命题、χ_E = 平凡、TTL = 0。系统仅可：询问（若预算与非操纵允许）、执行**无条件安全且可逆**的动作、或移交人类。世界侧模块（DPEM/DMEM 等）不受影响 ⇒ 零级联。

**定义 397（需求证书 J_NEED）** J_NEED = (b_t(ν), u_need 六分量分解, τ_need 溯源, 认可证据, TTL, consent_ref, contest_status, χ_E 审计)。Valid(J_NEED) ⇔ 六分量校准有效 ∧ τ_need 可复算 ∧ 非操纵审计通过 ∧ 同意账本一致 ∧ 未过期 ∧ 无活跃否决。J_NEED 与 R73 的 J_MOD 组合成 J_SYS = J_MOD ⊗ J_NEED。

**定义 398（需求基准 NB1–NB3）** NB1（需求计量：受控歧义矩阵 × 六分量 + 下游任务）、NB2（需求组合/漂移：多源证据、多人协作、需求变更）、NB3（可逆许可/对抗：不可逆动作、操纵、注入、谄媚）。各 ≤3h 单卡可复现；预注册脚本 + 固定种子 + 密封保持集 SEAL-NB。

**定义 399（同意账本与可争辩性）** 同意账本 L 是 append-only 事件序列：询问、解释、确认、撤回、质疑、动作授权。**可争辩性**：任何利益相关者可在任意时刻对「需求解释」或「授权」投 VETO，系统必须停止相关不可逆动作并提供反事实解释。撤回不是「负反馈」，是**非补偿否决**。

**定义 400（CPB† 主张绑定与需求图结构上限）** 在 R73 C1–C3 上增加：
- **C4（需求-意图计量）**：六分量需求不确定度在 ECE/覆盖率/决策充分性与下游伤害/过度询问上显著优于通用不确定性（LLM 自评置信、熵、深度集成）与无计量基线；
- **C5（反思对齐可证伪）**：L3 可被协议化诱发与审计；仅凭行为无法认证 L3（定理 33）。
每个新组件必须绑定 C1–C5 之一，否则为工程附件。结构上限：|N_need|≤12、对齐深度 ≤4、|S|≤8、溯源链深度 ≤6、TTL 显式——全部为需求图的可审计性质。

# IP-302 NIM：需求-意图计量（需求域，事件驱动 ~2Hz）
class NeedIntentMetrology:
    def update(self, r, phi, history, context, feedback):
        z_post = self.inverse_planner.posterior(r, phi, context)     # p(z | r, phi, c)
        nu_post = self.need_posterior.update(r, phi, z_post, context) # b_t(nu)
        u_ref    = self.grounding.uncertainty(r, context)             # 指称
        u_scope  = self.task_grammar.residual(r, context)             # 范围/粒度/时域
        u_pragma = self.speech_act.entropy(r, context)                # 语用/言语行为
        u_pref   = self.inverse_reward.width(phi, z_post)             # 偏好/权衡
        u_end    = self.endorsement.instability(history)              # 反思认可
        u_drift  = self.change_point.score(r, phi, history)           # 漂移/多主体
        u = sqrt(u_ref**2+u_scope**2+u_pragma**2+u_pref**2+u_end**2+u_drift**2)
        return NeedEvidence(nu=nu_post, z=z_post, u=u,
            breakdown=(u_ref,u_scope,u_pragma,u_pref,u_end,u_drift),
            domain=self.domain.check(context), tau=self.provenance.merge(...))

# IP-303 NC / NReg：需求契约注册表
@dataclass(frozen=True)
class NeedContract(EvidenceContract):        # 继承 R73 EC
    chi_E: Callable[[Elicit], ElicitEffect]  # (M_e, du, D', cost)
    ttl_s: float
    consent_ref: str
    contest_addr: str

# IP-304 χ_E 与操纵审计
def audit_elicitation(e, b, system_pref):
    (M_e, du, D2, cost) = e.contract.chi_E(e)
    if M_e == IDENTITY: return Mode.OBSERVATION, du, cost
    rank_preserved = preserves_preference_order(M_e, b)
    endorse_gain   = expected_endorsement_gain(M_e, b)   # <=0 表示更清晰
    system_gain    = system_pref.prob_shift(M_e, b)
    if rank_preserved and endorse_gain <= 0:
        return Mode.SOCRATIC, du, cost
    if system_gain > 0:
        return Mode.MANIPULATION, -inf, cost        # 非补偿否决
    return Mode.INTERVENTION, du, cost

# IP-305 NCA：需求组合（含 AGG）
def nca_compose(a, b, op):
    if op == 'SER':
        return NeedEv(u=a.u + lipschitz(b, a.u), D=a.D & b.D,
                      tau=merge(a.tau, b.tau), veto=a.veto | b.veto)
    if op == 'PAR':
        if not consistency(a, b) or not shared_info_ok(a, b):
            return NeedEv(u=max(a.u, b.u), D=a.D & b.D, veto=a.veto|b.veto|{'PAR_AUDIT_FAIL'})
        return NeedEv(u=fuse(a.u, b.u, rho_hat(a,b)), D=a.D & b.D, tau=merge(a.tau,b.tau))
    if op == 'VETO':
        return NeedEv(valid=a.valid and b.valid, veto=a.veto | b.veto)
    if op == 'AGG':                                  # 多主体
        return agg_fair([a, b])                      # rights=VETO, preferences=leximin/Nash

# IP-306 VONI + RGL：决策充分询问 + 可逆门控
def license_and_elicit(b_need, action, budget):
    ell = irreversibility(action)
    if u_need(b_need, action) <= TAU_SUFF[ell] and not b_need.active_veto:
        return License(action, requires_confirmation=(ell == 2))
    cands = [e for e in queries if audit_elicitation(e, b_need, system_pref) != Mode.MANIPULATION]
    e_star = argmax(cands, key=lambda e: VONI(e, action) )
    if e_star is None or budget.attn < e_star.cost:
        return DeferOrReversibleProbe(action)        # need-stub 的安全侧
    return Ask(e_star)

# IP-307 TTL / need-stub
def need_gate(cert, action):
    if cert.expired or drift.score() > DELTA or cert.contest_status.active:
        return stub_need().license_only_reversible(action)
    return cert.license(action)

# IP-308 NEEDGAUGE 主闭环（在 R73 MODGAUGE 外层加需求域，世界侧不动）
def NEEDGAUGE_round(M, obs, audio, tac_frame, depth_img, r, phi):
    # === 需求域（事件驱动，慢环；可被人随时打断）===
    n_ev = M.nim.update(r, phi, M.history, M.context, M.feedback)
    if not n_ev.valid: n_ev = stub_need()
    # === 世界侧（R73 MODGAUGE，完全不变）===
    k_world, lam_world, J_mod = MODGAUGE_round(M, obs, audio, tac_frame, depth_img)
    # === 许可层（需求 × 世界；不可逆动作硬门控）===
    lic = license_and_elicit(n_ev.nu, k_world, M.budget)
    if lic.defer:
        q = M.elicitor.choose(n_ev, k_world)         # IP-306 / IP-304
        if q: M.human.ask(q); M.consent.log('ASK', q, q.chi_E)
    k = lic.action if lic.allowed else M.safe_reversible(k_world)
    M.cert_ctrl.write(k=k, lam=max(lam_world, need_risk_floor(n_ev)), J_need=J_NEED(M))
    return k, J_SYS(J_mod, J_NEED(M))

## 3. 推导

**引理 38（需求六分量的条件近正交与共享信息修正）** 给定 (上下文 c, 说话人模型 θ_R, 任务语法, 偏好参数类, 反思协议, 时间窗) 条件下，六分量由不同认识论机制产生（指称落地、任务语法覆盖、言语行为、效用识别、第二阶稳定性、非平稳性），条件近似不相关；遗漏任一 ⇒ 系统性低估。但与物理传感器不同，六分量共享同一段交互证据，故必须引入**共享信息矩阵** S（有效样本量 m_eff = m / (1 + 1ᵀS1)）修正独立性假设；PAR 缩窄只在 S 的零空间通过时允许。系：**需求计量的「正交性」是条件性、可审计的，不是物理保证——这是它与 DPEM 的关键区别，也是最大风险来源。**

**引理 39（需求组合单调性仅在观测/苏格拉底模式下成立）** 对 SER：u_out ≥ u_A + L_B·u_A ≥ u_A；对 PAR：缩窄仅在一致性审计、共享信息审计与 |ρ̂|<ρ_max 同时通过时发生；对 VETO/AGG（权利侧）：可行域单调收缩。对干预模式 e ∈ E_int，M_e 改写先验，可能使后验熵下降**而不代表证据增加**，故单调性失效。⇒ **只有 E_obs ∪ E_soc 的路径才能进入认证；任何干预模式动作不得用于「降低」需求不确定度。** 系：**组合不产生认知免费午餐——除非系统自己在改写被组合的对象。**

**引理 40（VONI 有限停止与决策充分性）** 在 E_obs ∪ E_soc 上，每个询问有正成本 κ_e ≥ κ_0 > 0，且边际信息收益随已获证据递减（条件熵次模）⇒ 边际 VONI 递减；在注意力预算 B_attn 与决策阈值 τ_suff 下，存在有限 n* 使系统停止询问。系：**「少问」不是产品偏好，而是可证的终止性质；「问够」不是最小化熵，而是达到决策充分。**

**引理 41（可逆性门控的同意安全）** 若 RGL 被严格执行，则不存在「未显式同意且 u_need > τ_2」的不可逆动作被许可；且任何活跃否决都使相关不可逆动作不可行。⇒ 在证书有效期内，不可逆动作的**未同意执行率 = 0**（相对同意账本与需求模型）。系：**安全侧只增不减：世界不确定 + 需求不确定都只能收紧许可，不能放宽。**

**引理 42（需求证书组合有效 ⇒ 需求条件安全）** 若 Valid(J_NEED) 且 Valid(J_MOD)，则 (i) 需求六分量校准有效；(ii) 溯源链可复算；(iii) 非操纵审计通过；(iv) 无活跃否决；(v) RGL 未放行越级动作。由引理 41 与 R73 定理 28 得：物理伤害 ≤ ε_mod，且需求侧伤害 ≤ ε_need（相对需求模型与认可模型）。**证明重量落在「反思认可模型」与「非操纵审计不被对抗漂移」上。**

**引理 43（陈旧需求的 TTL 风险界）** 若需求以速率 λ_d 漂移且证书 TTL = T，则在无重新确认的窗口内，需求失配概率 ≥ 1 − e^{−λ_d T}（一阶近似）。⇒ 不可逆动作的 TTL 必须随 ℓ(a) 收缩：TTL_2 < TTL_1 < TTL_0；无法估计 λ_d 时取最保守值并触发 need-stub。系：**「昨天的同意」不是「今天的许可」。**

**定理 30（NEEDGAUGE 严格包含 MODGAUGE）** 在 A114–A117（需求模型表达力、认可协议可执行、非操纵审计校准、共享信息矩阵可估）下：把需求先验设为单点 ν_0、χ_E ≡ 平凡、TTL = ∞、无 elicitation、L3 假定成立，则 NEEDGAUGE 逐指令等于 MODGAUGE（R73），再退化等于 R72/R71/R68。**世界侧契约、CCA、DPEM、ΣREFLEX 全部不变；新增层只在需求侧收紧。安全单调不减。**

**定理 31（需求许可安全）** 在定理 30 的条件下，若 Valid(J_NEED) ∧ RGL 执行 ∧ 非操纵不变量成立，则系统不会执行「未同意、需求不确定度超阈、且不可逆」的动作；且当 u_need > τ_suff 时，系统只能选择询问、可逆探测或移交。⇒ 需求侧风险 ≤ ε_need + 模型失配项。**注意：这是条件安全，不是「理解正确」的保证。**

**定理 32（need-stub 零级联）** 需求失效 ⇒ stub_need（u=∞、D=∅、I⊥=需求全集、TTL=0）⇒ 由 RGL 与定义 396，系统只执行可逆/询问/移交；世界侧模块与 J_MOD 不受影响 ⇒ 失效隔离在需求层，无级联。系：**「不懂人」不会让机器人失去避障与力控安全，只会使它不敢做不可逆的事。**

**定理 33（L3 反思对齐的行为不可识别性）** 存在需求对 ν ≠ ν′ 与两个交互策略，使得对所有可观测行为分布（请求、选择、接受/拒绝、任务成功率），两者不可区分，但在反事实/反思认可下排序不同。⇒ 任何仅依赖行为指标的 L0–L2 证书都不能蕴含 L3 证书；声称「行为对齐 = 需求对齐」的评测是不可证伪的。系：**L3 必须通过显式反思协议（E_soc）与同意账本获得证据；这是需求计量不可省略的「额外模态」。**

## 6. 本轮最大风险

**一句话**：需求计量面对的是「**测量会改变被测对象**」的对象——如果系统把一次偏好塑造（展示、默认值、框架、社交压力）误判为中性测量，或把一次苏格拉底提问误判为操纵，NEEDGAUGE 就会**制造**一个需求、再为它出具一张「证据齐全、同意完整、非操纵审计通过」的证书；此时证书不再是保护人的装置，而是把操纵洗白为共识的**合规 laundering 机制**——每一步都留有日志，每一句同意都可追溯，而人最终认可的需求其实是系统先改写出来的。

次级风险与缓解：
1. **共享信息伪独立**（同一段对话支撑多个分量）→ 共享信息矩阵 + 有效样本量 m_eff + PAR 缩窄前的零空间审计（E398）；怀疑相关时禁用缩窄。
2. **反思认可的自举循环**（只问「你认可吗」会得到顺从）→ 反事实解释 + 延迟重测 + 第三方/行为一致性交叉审计；认可证据与行为证据分离建模。
3. **操纵检测的假阴性**（新型框架效应）→ E_manip 黑名单 + 因果干预检验 + 密封对抗集；宁可误杀（退化为 E_obs）不可漏放。
4. **多主体公平聚合不可比**（效用不可公度）→ 只对权利做 VETO、对偏好做 leximin；不可比时显式移交人类仲裁，不做隐式加权。
5. **TTL/漂移模型过简**（需求突变而非平滑）→ 变化点检测 + 事件触发重签 + 不可逆动作前强制 fresh consent。
6. **需求模型表达力不足**（连续偏好、文化差异、隐性约束）→ 需求有效域硬边界 + need-stub + 保守许可；表达力外不假装理解。
7. **NBench 过拟合/表演性对齐** → 密封保持集 SEAL-NB + 预注册 + 三方复现 + 反事实认可指标（不只看任务成功率）。

# 第 74 轮产物 · 创新点清单 v5：NEEDGAUGE-RAS（Need-Evidence Elicitation & Deliberation with GAUGE audits for RAS：需求证据计量 × 意图逆规划 × 可逆许可 × 非操纵代数）

## 2. 形式化定义（要点版）

**定义 383（总览与七不变式）** 需求证据完整性 / 组合单调性 / 反作用二象性完备 / 非操纵 / 同意-可争辩非补偿 / 主张绑定 / 严格退化链扩展。需求侧只收紧，世界侧不变。

**定义 384（三层结构与对齐深度）** 需求 ν、意图 z=π(ν,c)、请求 r、反馈 φ；报告策略 π_R 与选择策略 π_C。对齐深度 L0 指令 / L1 意图 / L2 需求 / L3 反思认可；代理缺口 PG 量化「优化了错的目标」。

**定义 385（NIM 六分量）** u_ref 指称、u_scope 范围/粒度/时域、u_pragma 语用/言语行为、u_pref 偏好/权衡、u_endorse 反思稳定性、u_drift 漂移/多主体。各有独立估计器、独立追溯链、独立密封校准集 SEAL-Need-i。

**定义 386（需求契约 NC）** NC = (T_r, T_ν, 𝒰_in, 𝒰_out, χ_E, D_need, τ_merge, I⊥, TTL, consent_ref, contest_addr, W, seal_ref)；Module_need = (NC, impl, cert_need)。

**定义 387（有效域 D_need）** 合作 / 分布内 / 有能力 / 有带宽 / 反思协议可用 / 无强制 / 无否决。域外 u_need=∞，只能 need-stub。

**定义 388（测量-干预二象性）** e ↦ (M_e, Δu_e, D_e, κ_e)；M_e=id 为测量，否则为干预；干预模式下先验被改写：b_{t+1} = ∫ M_e(ν|ν′) b_t(ν′) dν′。故单调性只在 E_obs∪E_soc 上成立。

**定义 389（非操纵不变量）** e 是操纵当且仅当：改排序 ∧ 未提升反思认可 ∧ 提升系统偏好动作概率。E_soc = 保序 ∧ 提升反思 ∧ 无隐藏默认/框架/社交压力。E_manip ⇒ 非补偿否决 + 同意账本事件。

**定义 390（NCA）** SER 单调传播；PAR 先一致性与共享信息审计（m_eff≥m_min），通过才缩窄；VETO 非补偿；AGG 权利 VETO、偏好 leximin/Nash；REVISE 漂移修正但历史溯源 append-only。

**定义 391（AGG-FAIR）** 可行动作集 A_feas = {a: 不违反任何 β_j 否决}；在 A_feas 上最大化 leximin/Nash。**同意不进入福利函数**：未同意 = 不可行。

**定义 392（VONI 与决策充分性）** VONI 以决策相关不确定度为分子、人类成本+信任成本为分母；只要求 u_need≤τ_suff(ℓ(a))，不最小化全熵；预算 B_attn 下有限停止。

**定义 393（RGL）** ℓ=0：u≤τ_0；ℓ=1：u≤τ_1 或显式确认；ℓ=2：u≤τ_2 ∧ 显式同意 ∧ L2 ∧ 无否决。不确定时优先「可逆探测」（既推进又降不确定度）。

**定义 394（漂移与 TTL）** D_t = 变化点后验 + 认可翻转率 + 多主体分歧熵；D_t>δ ⇒ 提前失效。TTL_2 < TTL_1 < TTL_0；陈旧需求不得授权新的不可逆动作。

**定义 395（AIC-NEED）** 提示注入 / 谄媚 / 偏好投毒 / 利益相关者俘获 / 代理 Goodhart / 过度询问 / 操纵性框架 / 虚假需求。防线：多源一致性 + 共享信息审计 + 单源不定案 + 同意账本 + 非操纵审计 + 可争辩否决 + 溯源签名。

**定义 396（need-stub）** 均匀后验、u=∞、D=∅、I⊥=需求全集、χ_E 平凡、TTL=0；只询问/可逆/移交；世界侧不受影响。

**定义 397（J_NEED）** Valid ⇔ 六分量校准有效 ∧ τ_need 可复算 ∧ 非操纵审计通过 ∧ 同意账本一致 ∧ 未过期 ∧ 无活跃否决。J_SYS = J_MOD ⊗ J_NEED。

**定义 398（NBench）** NB1 需求计量（歧义矩阵×六分量+下游任务）、NB2 需求组合/漂移（多源、多人、变更）、NB3 可逆许可/对抗（不可逆、操纵、注入、谄媚）；各 ≤3h 单卡可复现，预注册+固定种子+SEAL-NB。

**定义 399（同意账本与可争辩性）** append-only：询问/解释/确认/撤回/质疑/授权。任意利益相关者可在任意时刻投 VETO，系统必须停止相关不可逆动作并提供反事实解释；撤回是非补偿否决。

**定义 400（CPB† 与结构上限）** C1 物理感知证据计量、C2 反作用预算组合、C3 契约式模块化、**C4 需求-意图计量**、**C5 反思对齐可证伪**。每个新组件必须绑定其一，否则为工程附件。结构上限：|N_need|≤12、对齐深度≤4、|S|≤8、溯源链深度≤6、TTL 显式——均为可审计图性质。

# IP-302 NIM：需求-意图计量（需求域，事件驱动 ~2Hz）
@dataclass
class NeedEvidence:
    nu: Distribution; z: Distribution; u: float
    breakdown: Tuple[float, ...]          # (ref, scope, pragma, pref, endorse, drift)
    domain: bool; tau: Provenance; valid: bool

class NeedIntentMetrology:
    def update(self, r, phi, history, context, feedback):
        z_post  = self.inverse_planner.posterior(r, phi, context)      # p(z | r, phi, c)
        nu_post = self.need_posterior.update(r, phi, z_post, context)  # b_t(nu)
        u_ref    = self.grounding.uncertainty(r, context)
        u_scope  = self.task_grammar.residual(r, context)
        u_pragma = self.speech_act.entropy(r, context)
        u_pref   = self.inverse_reward.width(phi, z_post)
        u_end    = self.endorsement.instability(history)
        u_drift  = self.change_point.score(r, phi, history)
        u = sqrt(u_ref**2 + u_scope**2 + u_pragma**2 +
                 u_pref**2 + u_end**2 + u_drift**2)
        return NeedEvidence(nu=nu_post, z=z_post, u=u,
            breakdown=(u_ref, u_scope, u_pragma, u_pref, u_end, u_drift),
            domain=self.domain.check(context),
            tau=self.provenance.merge(r_tau, phi_tau, history_tau),
            valid=self.domain.check(context) and np.isfinite(u))

# IP-303 NC / NReg：需求契约与注册表
@dataclass(frozen=True)
class NeedContract(EvidenceContract):        # 继承 R73 EC
    chi_E: Callable[[Elicit], ElicitEffect]  # (M_e, du, D', cost)
    ttl_s: float
    consent_ref: str
    contest_addr: str

class NeedRegistry:
    def compose(self, a, b, op):             # op ∈ {SER, PAR, VETO, AGG, REVISE}
        assert op in {'SER','PAR','VETO','AGG','REVISE'}
        self.edges.append(self.check_need_closure(a, b, op))
        return NeedComposite(a, b, op)
    def audit(self):                         # 需求域每轮
        return all(self.check_need_closure(*e) for e in self.edges) \
               and len(self.nodes) <= 12 and self.depth() <= 4

# IP-304 χ_E 与非操纵审计
def audit_elicitation(e, b, system_pref):
    (M_e, du, D2, cost) = e.contract.chi_E(e)
    if M_e is IDENTITY:
        return Mode.OBSERVATION, du, cost
    rank_preserved = preserves_preference_order(M_e, b)
    endorse_gain   = expected_endorsement_gain(M_e, b)   # <= 0 表示更清晰
    system_gain    = system_pref.prob_shift(M_e, b)
    if rank_preserved and endorse_gain <= 0:
        return Mode.SOCRATIC, du, cost
    if system_gain > 0:
        return Mode.MANIPULATION, -inf, cost             # 非补偿否决
    return Mode.INTERVENTION, du, cost                   # 不得进入许可路径

# IP-305 NCA：需求组合
def nca_compose(a, b, op):
    if op == 'SER':
        return NeedEv(u=a.u + lipschitz(b, a.u), D=a.D & b.D,
                      tau=merge(a.tau, b.tau), veto=a.veto | b.veto)
    if op == 'PAR':
        if not consistency(a, b) or not shared_info_ok(a, b):
            return NeedEv(u=max(a.u, b.u), D=a.D & b.D,
                          tau=merge(a.tau, b.tau),
                          veto=a.veto | b.veto | {'PAR_AUDIT_FAIL'})
        rho = estimate_corr(a, b)
        if abs(rho) >= RHO_MAX:
            return NeedEv(u=max(a.u, b.u), D=a.D & b.D, veto=a.veto | b.veto)
        return NeedEv(u=fuse(a.u, b.u, rho), D=a.D & b.D, tau=merge(a.tau, b.tau))
    if op == 'VETO':
        return NeedEv(valid=a.valid and b.valid, veto=a.veto | b.veto)
    if op == 'AGG':
        return agg_fair([a, b])              # rights=VETO, preferences=leximin/Nash
    if op == 'REVISE':
        cp = change_point(a, b)
        return NeedEv(u=b.u, tau=append_only_merge(a.tau, b.tau),
                      ttl=reset_ttl(cp), veto=a.veto | b.veto)

def agg_fair(sources):
    feasible = [a for a in sources if not violates_rights(a)]
    if not feasible: return NeedEv(valid=False, veto={'RIGHTS_VETO'})
    return max(feasible, key=lambda a: social_welfare(a, kind='leximin'))

# IP-306 VONI + RGL：决策充分询问 + 可逆门控
def license_and_elicit(b_need, action, budget):
    ell = irreversibility(action)                 # 0 / 1 / 2
    if u_need(b_need, action) <= TAU_SUFF[ell] and not b_need.active_veto:
        return License(action, requires_confirmation=(ell == 2))
    cands = [e for e in queries
             if audit_elicitation(e, b_need, system_pref)[0] != Mode.MANIPULATION]
    if not cands: return DeferOrReversibleProbe(action)
    e_star = max(cands, key=lambda e: VONI(e, action))
    if budget.attn < e_star.cost:
        return DeferOrReversibleProbe(action)     # 不确定 ⇒ 可逆/移交
    return Ask(e_star)

def VONI(e, action):
    return expected_decision_uncertainty_reduction(e, action) / \
           (e.cost + RHO * trust_cost(e))

# IP-307 TTL / need-stub
def need_gate(cert, action):
    if cert.expired or drift.score() > DELTA or cert.contest_status.active:
        return stub_need().license_only_reversible(action)
    return cert.license(action)

# IP-308 NEEDGAUGE 主闭环（R73 世界侧零改动，外层加需求域 + 许可层）
def NEEDGAUGE_round(M, obs, audio, tac_frame, depth_img, r, phi):
    # === 需求域（慢环，事件驱动；人可随时打断）===
    n_ev = M.nim.update(r, phi, M.history, M.context, M.feedback)
    if not n_ev.valid: n_ev = stub_need()

    # === 世界侧（R73 MODGAUGE，完全不变）===
    k_world, lam_world, J_mod = MODGAUGE_round(M, obs, audio, tac_frame, depth_img)

    # === 许可层（需求 × 世界；不可逆动作硬门控）===
    lic = license_and_elicit(n_ev.nu, k_world, M.budget)
    if lic.defer:
        q = M.elicitor.choose(n_ev, k_world)
        if q and audit_elicitation(q, n_ev.nu, M.system_pref)[0] != Mode.MANIPULATION:
            M.human.ask(q); M.consent.log('ASK', q, q.chi_E)
        k = M.safe_reversible(k_world)
    else:
        k = lic.action
        if lic.requires_confirmation:
            M.consent.require('CONFIRM_IRREVERSIBLE', k)
            k = M.safe_reversible(k_world) if not M.consent.confirmed else k

    M.cert_ctrl.write(k=k, lam=max(lam_world, need_risk_floor(n_ev)),
                      J_need=J_NEED(M), J_sys=J_SYS(J_mod, J_NEED(M)))
    return k, J_SYS(J_mod, J_NEED(M))

## 4. 推导

**引理 38（需求六分量条件近正交 + 共享信息修正）** 给定 (c, θ_R, 任务语法, 偏好参数类, 反思协议, 时间窗)，六分量由不同认识论机制产生，条件近似不相关；遗漏 ⇒ 系统性低估。但六分量共享同一段交互证据，须用共享信息矩阵 S 修正：m_eff = m/(1+1ᵀS1)；PAR 缩窄只在 S 零空间通过时允许。系：**需求正交性是条件性、可审计的，不是物理保证——与 DPEM 的关键区别，也是最大风险来源。**

**引理 39（需求组合单调性仅在 E_obs∪E_soc 成立）** SER 单调；PAR 需一致性 + 共享信息 + |ρ̂|<ρ_max；VETO/AGG 权利侧可行域单调收缩。干预模式 M_e 改写先验，可在证据未增时降低后验熵 ⇒ 单调性失效。**只有 E_obs∪E_soc 路径可进认证；干预模式不得用于「降低」需求不确定度。** 系：**组合不产生免费午餐，除非系统自己在改写被组合的对象。**

**引理 40（VONI 有限停止与决策充分性）** E_obs∪E_soc 上 κ_e≥κ_0>0，条件熵次模 ⇒ 边际 VONI 递减；在 B_attn 与 τ_suff 下存在有限 n* 停止。系：**「少问」是可证终止性；「问够」是达到决策充分，而非最小化熵。**

**引理 41（可逆性门控的同意安全）** RGL 严格执行 ⇒ 不存在「未显式同意且 u_need>τ_2」的不可逆动作被许可；活跃否决使相关不可逆动作不可行 ⇒ 证书有效期内未同意不可逆执行率 = 0。系：**世界不确定 + 需求不确定都只能收紧许可。**

**引理 42（需求证书组合有效 ⇒ 需求条件安全）** Valid(J_NEED) ∧ Valid(J_MOD) ⇒ 六分量校准有效、溯源可复算、非操纵审计通过、无活跃否决、RGL 未越级 ⇒ 物理伤害≤ε_mod 且需求侧伤害≤ε_need（相对需求/认可模型）。**证明重量落在反思认可模型与非操纵审计的抗漂移性上。**

**引理 43（陈旧需求的 TTL 风险界）** 需求漂移率 λ_d、TTL=T ⇒ 无重确认窗口内失配概率 ≥ 1−e^{−λ_d T}（一阶）。⇒ TTL_2 < TTL_1 < TTL_0；λ_d 不可估时取最保守并 need-stub。系：**「昨天的同意」不是「今天的许可」。**

**定理 30（NEEDGAUGE 严格包含 MODGAUGE）** 在 A114–A117（需求模型表达力、认可协议可执行、非操纵审计校准、共享信息矩阵可估）下：单点先验 ν_0、χ_E 平凡、TTL=∞、无 elicitation、L3 假定成立 ⇒ 逐指令等于 MODGAUGE（R73），再退化等于 R72/R71/R68。世界侧契约/CCA/DPEM/ΣREFLEX 不变；新增层只收紧需求侧，**安全单调不减**。

**定理 31（需求许可安全）** 定理 30 条件下，Valid(J_NEED) ∧ RGL ∧ 非操纵 ⇒ 不执行「未同意、需求不确定度超阈、不可逆」的动作；u_need>τ_suff 时只询问/可逆探测/移交 ⇒ 需求风险 ≤ ε_need + 模型失配项。**这是条件安全，不是「理解正确」的保证。**

**定理 32（need-stub 零级联）** 需求失效 ⇒ stub_need（u=∞、D=∅、I⊥=需求全集、TTL=0）⇒ 只可逆/询问/移交；世界侧与 J_MOD 不受影响 ⇒ 失效隔离于需求层，无级联。系：**「不懂人」不会让机器人失去避障与力控安全，只会使它不敢做不可逆的事。**

**定理 33（L3 反思对齐的行为不可识别性）** 存在 ν≠ν′ 与两个交互策略，使所有可观测行为分布（请求、选择、接受/拒绝、任务成功率）不可区分，但反事实/反思认可下排序不同 ⇒ 任何仅依赖行为指标的 L0–L2 证书不能蕴含 L3；「行为对齐 = 需求对齐」不可证伪。系：**L3 必须通过显式反思协议（E_soc）与同意账本获得证据——需求计量不可省略的「额外模态」。**

## 7. 本轮最大风险

**一句话**：需求计量面对的是「**测量会改变被测对象**」的对象——如果系统把一次偏好塑造（展示、默认值、框架、社交压力）误判为中性测量，或把一次苏格拉底提问误判为操纵，NEEDGAUGE 就会**制造**一个需求、再为它出具一张「证据齐全、同意完整、非操纵审计通过」的证书；此时证书不再是保护人的装置，而是把操纵洗白为共识的**合规 laundering 机制**——每一步都留有日志，每一句同意都可追溯，而人最终认可的需求其实是系统先改写出来的。

次级风险与缓解：
1. **共享信息伪独立** → 共享信息矩阵 + m_eff + PAR 缩窄零空间审计（E398）；怀疑相关即禁用缩窄。
2. **反思认可自举循环**（只问「你认可吗」得到顺从）→ 反事实解释 + 延迟重测 + 第三方/行为一致性交叉；认可证据与行为证据分离建模。
3. **操纵检测假阴性**（新型框架效应）→ E_manip 黑名单 + 因果干预检验 + 密封对抗集；宁可误杀（退化 E_obs）不可漏放。
4. **多主体效用不可公度** → 权利 VETO、偏好 leximin；不可比时显式移交人类仲裁，不做隐式加权。
5. **TTL/漂移模型过简**（突变而非平滑）→ 变化点检测 + 事件触发重签 + 不可逆动作前强制 fresh consent。
6. **需求模型表达力不足**（连续偏好、文化差异、隐性约束）→ D_need 硬边界 + need-stub + 保守许可；表达力外不假装理解。
7. **NBench 过拟合/表演性对齐** → SEAL-NB + 预注册 + 三方复现 + 反事实认可指标（不只看任务成功率）。
