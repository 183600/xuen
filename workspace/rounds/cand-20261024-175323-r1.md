# 第 8 轮 · PULSE：可用性评估是策略的自检回路，Isaac Sim 是前置检查器，本体感知是运行时证据

> 检索/复核日期：2026-10-24（UTC）。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「可用性评估」「Isaac Sim」「本体感知」。我把它们合成一个主判断：**在单次成功率约 30% 的 regime 里，最大的边际收益不是把第一次尝试从 30% 做到 35%，而是让策略知道自己正在失败、并在 180 秒内再试一次；"可用性评估"应被转译为策略的自可用性（self-usability）——执行前查"这个动作在当前本体/场景/时延下是否可执行"，执行中查"动作是否按预期产生了结果"，执行后查"目标状态是否真的成立"；Isaac Sim 提供前两项的几何 oracle 与扰动数据，本体感知提供运行时的证据。** 这也是对第 7 轮的一次修正：第 7 轮把 39.8% 的步骤权重当成主预算依据之一，但手册明确"成功率优先、步骤分只在成功率相同时比较"，所以终局放置的价值主要来自成功闸门，而不是 39.8% 的步骤权重；步骤分降级为 tiebreak 与诊断，不再占用主预算。

## 0. 本轮先核实：六个新事实/修正

### 0.1 评分规则：10 次/任务、5 轴各 2 次、成功率优先、步骤分仅 tiebreak、180 秒
手册原文（[S12]，2026-10-24 抓取）：

- 通才模型必须完成全部 32 个任务；每个任务在**不同的泛化评测场景中进行 10 次测试**，计算每个任务的平均成功率和平均过程分，计入排行榜。
- 10 次运行包含 **5 种泛化类型，每种类型各 2 次**：位置、干扰物、桌面背景、未见物品、人为干扰。
- 排序规则：**按 32 个任务的总平均成功率排序；成功率相同时按总平均步骤分排序；若仍相同，提交日期较早的模型靠前。**
- 单任务真机执行**最大 180 秒**，超时记失败，并按执行情况计算步骤分。
- 仅通才模型进榜；另有**不计分的单任务测试通道**（[S8]），可用于真机调试。
- **所有任务须基于同一模型完成，不得混合使用多个模型一起测试**；模型类型不限（World Model、VLA 均可）。

这条修正很重要：第 7 轮的"终局放置 = 闸门 + 39.8% 步骤分"仍然成立，但 **39.8% 是 tiebreak 权重，不是与成功率并列的目标**。在成功率约 30%、大量模型并列低分的榜单上，先把成功率抬上去，比在同样的成功率下多拿几个步骤分更划算；步骤分是"成功率相同之后"的第二个杠杆。

### 0.2 官方把"交互质量/结果可信度"写进了评测记录
提交 README §6（[S6]）明确：评测时策略通过网络被逐步查询，**每次 `get_action` 的响应时延、时延波动、返回动作的统计规律性**会被记录；这些信息可能随成绩一起展示，用于判断交互质量与结果可信度。动作格式还规定 `action_chunk_size` 是 metadata 中的固定正整数，chunk 内的动作由评测端连续执行，直到下一次 `get_action`。

这带来两个设计约束：
- **不能靠"每步重规划"来绕过接口约束地提高反应性**；chunk 是固定的，chunk 内是开环的。我们要在"chunk 边界"做监测与选择，而不是在 chunk 内做高频闭环。
- **动作要平滑、时延要稳定**；监测器的 abort/retry 不能表现为剧烈抖动或异常的长尾时延，否则会被交互质量记录抓住。可用性评估必须同时报告 p50/p99 时延与动作 jerk。

### 0.3 榜单页现在标 "Live"，但数据仍是 `gen_leaderboard.py` 生成的演示数据
`leaderboard.html` 现在写 "Ranking · Live"（[S10]），`leaderboard_data.json` 仍有 `"generated_from": "gen_leaderboard.py"`，包含 8 个模型 × 32 任务 = 256 条 `task_metrics`；榜首 MolmoAct2/DexHacker 为 **29.7% 成功率 / 39.0 步骤分 / 44.02 秒平均时长**，第 8 名 GR00T N1.5 为 20.5% / 28.1。模型名是真实模型名；文件没有真实提交时间/运行日志，用户名与指标呈演示性质（推断）。

**处理方式**：把它当作"榜首约 30%、平均一局约 44 秒"的**弱先验**，不当作真实排名结论。本轮的工作前提"榜首不到 30%"与这份演示数据一致；即便真实榜首略高，下面的重试经济学在"低成功率 + 180 秒 + 10 次/任务"的结构下仍然成立。

### 0.4 数据与任务信息仍是公开的 33k / 32 任务 / 5 复述
- HF collection `unibot-v1-challenge-dataset`（[S3]）：32 个数据集，969–1,530 条/任务，合计约 33k、169h；HangCup 实测 1,043 条 / 194,564 帧 / 30fps，`lastModified` 2026-10-14（[S4]）。
- 每个任务在 `meta/tasks.parquet` 里有 **5 条英文复述**（`@` 分隔；[S5]），评测指令可能在其中采样。
- `tasks_v2/<slug>/info.json`（[S2]）给出 `score_steps`（满分 100）、`generalization` 的 `unseen_object_3` / `human_1_note` / `human_4_note`、难度、episodes。
- 32 个终局步骤合计 1275/3200 = **39.8%**；放置/插入/堆叠/闭合类步骤约 59.7%；难度 12 Easy / 12 Medium / 8 Hard；步骤数 2–5。

**新用法**：这些数据不只是"训练 VLA"的燃料，更是 **PAM 的名义动力学训练集**——33k 条成功轨迹足够学"正常动作-观测关系"，而失败检测只需要正常数据 + 一个残差阈值。这是本轮可行性最重要的支撑。

### 0.5 官方 Isaac Sim 栈能做什么、不能做什么
官方 `unitree_sim_isaaclab`（Apache 2.0，[S13]）提供 G1-29dof-Dex1 的 `G129_CFG_WITH_DEX1_BASE_FIX`（base 固定，decimation=2 × dt=0.005 → **100Hz**）与 `G129_CFG_WITH_DEX1_WHOLEBODY`（wholebody，decimation=4 → **50Hz**）；有 pick-place cylinder / red block / stack 等场景，支持 `--replay`、`--generate_data`、`--modify_light`、`--modify_camera`；前视 + 双腕相机。

但它**不是评测的数字孪生**：没有 32 任务场景、没有同样的双高相机机位、没有同样的物体/桌面/背景资产、没有评测端的控制栈与时延。它能做的是：
1. **运动学/碰撞 oracle**：给定候选 EE 位姿，查 G1 的 IK 可达性、关节限位余量、自碰撞/桌面碰撞/物体碰撞；
2. **扰动数据发生器**：在成功轨迹上随机化物性/PD/时延/外力，生成"名义 vs 扰动"的本体感知残差，用于训练/校准 PAM；
3. **不**适合做像素级 VLA 训练数据（域差大、无 32 任务孪生）。

### 0.6 G1 本体感知的"可见面"与"不可见面"
G1 是 29 DoF（双臂各 7、腰 3、腿 12），低层 `MotorState_` 有 `q, dq, ddq, tau_est`，但**提交 API 只暴露位置**：双臂各 7 关节、左右 EE 6D 位姿、左右夹爪 1D、`lower_body` 15D；没有时间戳、速度、力矩、触觉（[S6]）。因此：
- 速度只能由堆叠帧差分近似，且采样周期未知 → 用**归一化伪速度/残差形状**，不要依赖绝对物理单位；
- 接触力不可见 → 用**指令-观测跟踪误差**、**夹爪开度**、**EE 位姿偏差**做接触代理；
- 夹爪开度是抓取成功/失败的直接信号：闭合指令后开度仍接近 0 → 抓空；提起后开度突降 → 滑落。
- 这恰好是 PAM 的输入域：**本体感知 + 动作指令**，不需要像素，也不受背景/光照影响。

## 1. 三个灵感词，各自钉到事实上

### 1.1 可用性评估：从 HCI 的用户测试，转译为策略的自可用性（self-usability）
"可用性"在 HCI 里是"用户能否有效、高效、满意地完成任务"。把"用户"换成"策略自身"，就得到三个可计算的问题：

| 阶段 | 问题 | 可用信号 | 失败时的动作 |
|---|---|---|---|
| 执行前 pre-flight | 这个动作/目标位姿在当前本体、桌面、障碍下**可执行**吗？ | Isaac Sim IK/碰撞/关节限位/可见性；候选 EE 位姿 | 换候选、调 pivot/腰、重新抓取 |
| 执行中 in-flight | 动作**正在按预期产生结果**吗？ | 本体感知残差、跟踪误差、夹爪开度、SSG 谓词 | 早停、诊断、重试/恢复 |
| 执行后 post-flight | 目标状态**真的成立**吗？ | 稳定位移、谓词、视觉复核 | nudge/regrasp/重放 |
| 系统级 system | 交互本身**可用**吗？ | 时延 p50/p99、jerk、chunk 规律性、重试次数 | 降 K、降分辨率、回退 |

这不是把"可用性"当形容词，而是把它变成**一组可测量的闸门**：pre-flight 的 IK/碰撞通过率、in-flight 的检测召回@误报、post-flight 的 settle 位移、system 的 p99 时延。每一项都能在离线/仿真/调试槽上量出来，并写进 **Usability Card**（本轮新增的过程产物）。

### 1.2 Isaac Sim：不是数字孪生，是前置检查器 + 扰动发生器
我把 Isaac Sim 的用途收窄到两个**与像素无关**的角色：

1. **USIM（Usability Sim Check）**：策略在输出 chunk 前，把候选的终局 EE 位姿送进一个快速的 IK/碰撞检查器。检查器可以用 Isaac Sim 的 G1 资产与关节限位，也可以退化到解析 IK + 胶囊碰撞（只用官方 URDF）。输出不是图像，而是**可达性 margin、碰撞 margin、关节限位 margin**。这一步把"放置目标不可达/会撞桌子/会撞自己"这类失败在执行前挡掉。
2. **PAM 的扰动数据**：在官方成功轨迹上，随机化物体质量/摩擦、PD 增益、控制时延、外力脉冲、夹爪摩擦，生成"名义 vs 扰动"的本体感知序列。PAM 只用成功数据训练（学名义动力学），扰动数据只用于**验证/校准**它的残差阈值。这避免了"需要大量真实失败标注"的死结。

**不做的**：全 32 任务高保真孪生、像素级 sim 训练、运行时 sim/MPC、sim RL。这些在第 5–7 轮已经反复论证过性价比低，本轮继续砍。

### 1.3 本体感知：免费的运行时证据，但不是万能
本体感知的优势：
- **低维、低时延、不受背景/光照/遮挡影响**；G1 的 7+7 关节 + 2 夹爪 + 15 lower_body 足够描述"动作有没有被执行、有没有被卡住、有没有抓住"。
- 官方 33k 成功轨迹是现成的名义动力学数据；PAM 可以只用成功数据训练，**不需要失败标签**。
- 失败检测的文献一致指向本体感知的早期性：KIT 的手部本体感知在 **50% 执行时间**达到 **96.97%** 准确率（[S31]）；RAPT 在 G1 上 50Hz 纯本体感知监测（[S34]）；ProTracer 用本体感知定位 failure onset（[S32]）。

本体感知的盲区：
- **语义错误**（拿错物体、去错目标）它看不见；必须配 SSG 的视觉谓词。
- **接触力/滑移**只能间接推断；夹爪开度 + 跟踪误差是代理，不是真值。
- **小数据下本体感知可能有害**：ContactGuard 发现本体输入在小数据 regime 会拖累监测（[S36]）；GAP 发现本体感知会在运动过渡段压制视觉（[S37]）。所以本轮的设计原则是：**本体感知只进监测头，不进动作主干**；动作策略仍然是视觉-语言主导。

## 2. 主判断：重试经济学

### 2.1 单次 vs 多次：公式与表
设单次尝试成功率 \(p\)，监测器在失败后能检测到的概率 \(d\)，检测后重试的成功率 \(r\)，最多 \(N\) 次尝试，则近似：

\[
P_N = 1 - (1-p)\left[1 - d r\right]^{N-1}
\]

取 \(p=0.3\)：

| 设定 | N=1 | N=2 | N=3 | N=4 |
|---|---:|---:|---:|---:|
| 无监测（d=0） | 30.0% | 30.0% | 30.0% | 30.0% |
| d=0.8, r=0.3 | 30.0% | **46.8%** | **59.6%** | **69.3%** |
| d=0.6, r=0.25 | 30.0% | 40.5% | 49.4% | 57.0% |
| d=1.0, r=0.3（上界） | 30.0% | 51.0% | 65.7% | 76.0% |

关键不是公式的精确性，而是**量级**：即使检测召回只有 0.6、重试成功率只有 0.25，2–3 次机会也能把 30% 抬到 40–50%；如果检测召回 0.8，2 次就接近 47%，3 次接近 60%。这比"把第一次从 30% 做到 35%"大一个量级。

### 2.2 时间预算：180 秒够不够？
- 演示数据 HangCup 的 episode 中位约 5.9 秒；演示榜的平均一局约 44 秒（含失败/超时/慢策略），说明**策略执行远慢于演示**。
- 若一次完整尝试 30–45 秒，180 秒可容纳 4–6 次；若在失败后 50% 时间内早停，单次失败成本 15–22 秒，可容纳 6–8 次。
- chunk 周期：若 \(T_a=8\)、控制 10–20Hz，一个 chunk 约 0.4–0.8 秒；PAM 在 chunk 边界检测，**检测延迟目标 ≤1–2 个 chunk**，远快于"等到 episode 结束"。
- 真正的瓶颈不是算力，而是**失败的可观测性**：滑落要等提起，插入要等接触，人为干扰要等下一次视觉/本体变化。所以 TTR 不能假设"随时可检测"，而要估计"这个失败类型需要多少秒才能被确认"。

**结论**：180 秒足以做 2–3 次有意义的尝试，但不足以做"无限重试"。TTR 的职责是把时间花在"高失败概率 + 高重试收益"的尝试上，而不是平均主义地重试。

### 2.3 统计功效：为什么必须追求 10pp 级效果，而不是 3pp 级微调
- 320 episodes（32 任务 × 10 次），单次成功率 \(p=0.3\) 时，单臂标准误 \(SE=\sqrt{0.3\times0.7/320}=2.56pp\)。
- 两次独立提交的差值 \(SE\approx3.62pp\)；要检测 +5pp，双侧 α=0.05 的功效只有约 **28%**；+10pp 约 **76%**；+15pp 约 **97%**。
- 结论：**榜单无法可靠区分 3–5pp 的微优化**；只有 10pp 级的效果才值得押注。重试经济学的预期增益是 10–20pp，正好落在这个可检测区间；而"把第一次成功率提高 3pp"的微优化，即使真的有效，也可能被噪声淹没。

> 这不是说微优化没用，而是说**预算应该先花在能被榜单看见的杠杆上**。重试是那个杠杆；步骤分/放置精度是成功率相同之后的第二杠杆。

### 2.4 与"提高第一次成功率"的对比
| 路线 | 典型增益 | 成本 | 可检测性 | 风险 |
|---|---:|---|---|---|
| 第一次 +5pp（更好的 VLA/数据） | +5pp | 高（训练/数据/算力） | 低（功效 ~28%） | 过拟合、域差 |
| 监测 + 2–3 次重试 | +10–20pp | 低–中（监测头 + 调度） | 高（功效 >76%） | 误报、时间预算、合规 |
| 步骤分微调（放置精度） | +tiebreak | 中 | 只对并列有效 | 不改变成功闸门 |

**本轮押注：先做重试，再做放置精度。** 重试是"乘法"，放置是"加法"；在 30% 的基数上，乘法的边际更大。

## 3. PULSE 轮廓（细节在产物区）

PULSE = **P**roprioceptive **U**sability **L**oop for **S**elf-**E**valuation。四个组件：

1. **USIM（pre-flight）**：候选终局 EE 位姿 → IK 可达性/碰撞/关节限位 margin。不可行就换候选/调 pivot/换抓取。用 Isaac Sim 资产或解析 IK 兜底。
2. **PAM（in-flight）**：在 chunk 边界，用"本体历史 + 上一个 chunk 的动作"预测"下一个 chunk 的本体轨迹"；实际观测与预测的残差超过 conformal 阈值 → 失败/异常。输出失败类型（抓空/滑落/卡住/碰撞/人为干扰）与置信度。
3. **UAVS（selection）**：当有 K 个候选 chunk（K=2，优先只用在终局放置步），用 USIM margin + PAM 预测残差 + 进度/视觉谓词打分，选最"可用"的一个。K=1 时退化为"检查 + 监测"。
4. **TTR（time-to-recovery）**：根据剩余时间、失败概率、重试成功率，决定"继续/早停重试/主动探测/保守完成"；重试从**最后一个已验证步骤**开始，而不是从头开始。

与第 7 轮组件的关系：

| 组件 | 本轮状态 | 说明 |
|---|---|---|
| GPR-VLA 主干 + WLA 底座 | 保留 | 唯一学习型动作模型；PAM 是辅助头，不引入第二个动作模型 |
| SSG 评分步骤图 | 降级为"步骤状态机 + 视觉谓词" | 为 TTR 提供"从哪一步重试"；不再单独押注 |
| PGL 放置目标阶梯 | 保留，支撑 | 为 USIM/UAVS 提供候选放置位姿 |
| OPT 放置位姿迁移 | 保留，支撑 | 为 USIM 提供先验目标；不再主押 |
| ICR 检索上下文 | 保留，降级 | 延迟允许才开；p99 超标就关 |
| SVL 落点闭环 | **升级** | 变成 PULSE 的 post-flight 阶段：稳定检测 + nudge/regrasp |
| NRB 官方备注恢复 | 保留，转为测试/训练集 | human_1/human_4 剧本是 PAM/TTR 的真实验证用例 |
| L2L 产学研数据农场 | **降级/延后** | 规则未确认外部数据；本轮主杠杆在运行时，不在数据规模 |
| 全 32 任务孪生 / 自由 sim 数据 | 砍 | 官方 sim 无 32 任务；域差大 |
| 独立监测模型 | 砍 | 违反"同一模型"风险；PAM 做成同一 checkpoint 的辅助头 |
| 自适应 chunk size | 砍 | metadata 固定，接口不允许 |

## 4. 风险与合规（先立后破）

| 风险 | 概率 | 影响 | 缓解 | 停止条件 |
|---|---|---|---|---|
| PAM 只能测执行失败，测不了语义错误 | 高 | 中 | 与 SSG 视觉谓词并联；语义错误走视觉/重规划 | 语义失败占比 >50% → 回退 SSG+PGL |
| 误报导致无谓重试 | 中 | 高 | conformal 校准 α=5%；TTR 只在"剩余时间足够"时早停 | 误报 >10% → 提高阈值/关 PAM |
| 灾难性失败不可重试（物体掉地） | 中 | 高 | pre-flight 碰撞检查 + 保守运输 + 不做高风险探测 | 掉落率不降 → 加 USIM/降速 |
| 180 秒不够 | 中 | 中 | 早停 + 从已验证步骤重试 + 长任务限 1 次 | 平均重试 >2 次仍不涨 → 关 TTR |
| 时延/动作规律性被记录 | 中 | 中 | p99 门控；abort 平滑；chunk 边界才决策 | p99 超基线 +20ms 或 jerk 超演示 95 分位 → 降 K/关 UAVS |
| 规则不允许外部 sim/数据 | 中 | 高 | USIM 用解析 IK 兜底；sim 只做离线开发；默认不外采 | 明确禁止 → 只用官方数据 + 解析检查 |
| 单模型审计 | 中 | 高 | PAM 做同一 checkpoint 的辅助头；其余确定性代码；模型卡披露 | 审计不过 → 只保留确定性 USIM/TTR |
| 演示榜不是真实榜 | 高 | 中 | 用调试槽/计分跑校准；不把 29.7% 当真实事实 | 真实榜发布 → 重跑先验 |

**合规底线**：不把 PAM 做成独立模型；不把 Isaac Sim 放进推理路径；不依赖未确认的外部数据；所有确定性组件（USIM/TTR/SSG）在模型卡中披露；动作平滑、时延稳定，避免被交互质量记录判为异常。

## 5. 一句话押注

**把"可用性评估"做成策略的运行时自检回路：用 Isaac Sim 做前置可达/碰撞检查，用本体感知做动作-结果残差监测，用诊断驱动的重试把 180 秒变成 2–3 次机会——这是把不到 30% 的单次成功率抬到 40–60% 的最便宜杠杆。**

## 0. 产物摘要

### 0.1 一句话
**PULSE（Proprioceptive Usability Loop for Self-Evaluation）**：在动作主干不变的前提下，给策略加一个"执行前几何检查（USIM）→ 执行中本体残差监测（PAM）→ 候选动作选择（UAVS）→ 时间预算重试（TTR）"的自可用性回路，把 30% 的单次成功率通过 2–3 次**可检测的重试**抬到 40–60%。

### 0.2 组件与是否进推理

| 组件 | 作用 | 是否进推理 | 学习/确定性 | 新增算力 |
|---|---|---|---|---|
| GPR-VLA + WLA 底座 | 唯一动作策略 | 是 | 学习（已有） | 基线 |
| SSG 步骤状态机 | 当前步骤/已验证步骤/谓词 | 是 | 确定性 + 小谓词头 | <1ms |
| PGL 放置目标 | 候选放置位姿 | 是 | 学习/检索 | 基线 |
| OPT 放置位姿迁移 | 候选先验 | 是 | 检索/统计 | <1ms |
| **USIM** | IK/碰撞/限位 margin | 是（仅终局/关键步） | 确定性（IK/碰撞） | <2ms/候选 |
| **PAM** | 本体动作-结果残差 | 是（chunk 边界） | 学习（辅助头） | <5ms |
| **UAVS** | K 候选打分选择 | 是（K=2，仅终局） | 确定性打分 | 1 次额外 VLA 前向（可选） |

| SVL | 释放后稳定/谓词复核 | 是 | 确定性 + 谓词 | <5ms |
| ICR | 检索上下文 | 可选 | 学习/检索 | 缓存命中时 <10ms |
| DebugLoop | 真机调试槽 | 否 | 流程 | — |
| Usability Card | 评测记录 | 否 | 流程 | — |

### 0.3 预期收益（可证伪）
- **主收益**：在 30% 单次成功率、检测召回 0.8、重试成功率 0.3 的假设下，2 次尝试 46.8%、3 次 59.6%；保守假设（d=0.6, r=0.25）也有 40.5%/49.4%。
- **次收益**：USIM 挡掉不可达/碰撞的终局放置，预期把终局步失败率降 10–20%（离线/仿真可测）。
- **tiebreak**：SVL + 放置精度提升步骤分，但只在成功率相同后起作用；不作为主预算。
- **可证伪点**：如果 PAM 在留出扰动集上的 TPR@FPR=5% <60%，或调试槽上早停后重试成功率 <20%，则主收益不成立，回退到 USIM+SVL（不做重试）。

- 不要用"每步重规划"规避 chunk；接口不允许，且会被交互质量记录。

## 2. 评分算术与重试经济学

### 2.1 成功率优先，步骤分是第二杠杆
设任务 \(i\) 的成功率为 \(s_i\)，步骤分为 \(m_i\)，排名键为：

\[
\text{rank} = \left(\frac{1}{32}\sum_i s_i,\ \frac{1}{32}\sum_i m_i,\ -\text{submit\_date}\right)
\]

字典序：先比平均成功率，再比平均步骤分。因此：
- 终局步是**成功闸门**（所有任务成功=全部步骤完成），它同时影响 \(s_i\) 和 \(m_i\)；
- 中间步只影响 \(m_i\)，只在 \(s_i\) 相同的模型之间起作用；
- 在成功率约 30% 的区间，模型之间更容易在成功率上拉开差距，而不是在步骤分上；**先做成功率，再做步骤分**。

**弱先验**：演示榜的"步骤分 − 成功率"约 +8.6pp（39.0−29.7 等），说明失败集中在后段步骤；这与"终局是闸门"一致。但这是生成数据，只当弱先验。

### 2.2 重试公式与表
设单次成功率 \(p\)，失败检测召回 \(d\)，检测后重试成功率 \(r\)，最多 \(N\) 次：

\[
P_N = 1 - (1-p)\left[1 - d r\right]^{N-1}
\]

假设：失败可被独立检测；检测后立即早停；重试从失败步开始；忽略误报占用的时间（实际会用 TTR 扣掉）。取 \(p=0.3\)：

| 设定 | N=1 | N=2 | N=3 | N=4 | N=5 |
|---|---:|---:|---:|---:|---:|
| 无监测 d=0 | 30.0% | 30.0% | 30.0% | 30.0% | 30.0% |
| d=0.8, r=0.3 | 30.0% | **46.8%** | **59.6%** | **69.3%** | 76.6% |
| d=0.6, r=0.25 | 30.0% | 40.5% | 49.4% | 57.0% | 63.5% |
| d=0.5, r=0.2 | 30.0% | 37.0% | 43.3% | 49.0% | 54.1% |
| d=1.0, r=0.3（上界） | 30.0% | 51.0% | 65.7% | 76.0% | 83.2% |

**读法**：
- 即使检测召回只有 0.5、重试成功率只有 0.2，2 次也能 +7pp、3 次 +13pp——仍然大于 5pp 的微优化。
- 检测召回从 0.5 提到 0.8，3 次从 42% 提到 60%，**监测质量比第一次成功率更值钱**。
- 重试成功率 \(r\) 不一定等于 \(p\)：从失败步重试通常比从零开始高（已完成的步骤不复位），但被抓空/滑落后重试可能更低；用 \(r=0.25\)–0.35 做区间。

**误报的代价**：如果误报率 \(f\)，一次成功尝试被误判为失败，会浪费 \(T_{waste}\) 并可能把成功变成失败。净收益条件近似：

\[
(1-p) d r - p f > 0
\]

在 \(p=0.3, d=0.8, r=0.3\) 时，\(0.7\times0.8\times0.3=0.168\)；允许 \(f < 0.168/0.3 = 56\%\) 才不亏——这个条件很松，说明**只要误报不接近 50%，重试就是正期望**。但误报会消耗时间，实际阈值应更严（目标 FPR ≤5–10%）。

### 2.3 时间预算：180 秒够 2–3 次有意义的重试
- 演示数据 HangCup episode 中位约 5.9 秒；演示榜平均一局约 44 秒（含失败/慢策略）。
- 若一次完整尝试 30–45 秒，180 秒可容纳 4–6 次；若失败后 50% 时间早停，失败成本 15–22 秒，可容纳 6–8 次。
- chunk 周期：\(T_a=8\)，控制 10–20Hz → 0.4–0.8 秒/chunk；PAM 在 chunk 边界检测，目标延迟 ≤1–2 chunk。
- 失败的可观测时间不同：抓空在闭合后 0.5–1 秒可判；滑落在提起后 1–2 秒；插入卡住在接触后 1–3 秒；人为干扰在下一次视觉/本体变化。TTR 要为每类失败估 \(T_{confirm}\)，不能假设"立即检测"。
- 长任务（4–5 步）的重试预算更紧：只重试当前步，最多 1 次；短任务（2–3 步）可 2 次。

**结论**：180 秒足以做 2–3 次有意义的尝试；重试不是"无限试错"，而是"把时间从低概率尝试转移到高概率尝试"。

### 2.4 统计功效：为什么必须追求 10pp 级效果
- 320 episodes（32×10），\(p=0.3\)：单臂 \(SE=\sqrt{0.3\times0.7/320}=2.56pp\)。
- 两次独立提交差值 \(SE\approx3.62pp\)。
- 双侧 α=0.05 的功效：

| 真实提升 | 差值 SE | z | 近似功效 |
|---|---:|---:|---:|
| +3pp | 3.62pp | 0.83 | ~20% |
| +5pp | 3.62pp | 1.38 | ~28% |
| +10pp | 3.75pp | 2.67 | ~76% |
| +15pp | 3.78pp | 3.97 | ~97% |

- **结论**：3–5pp 的微优化在 320 episodes 上基本不可检测；10pp 级以上才值得押注。重试的预期增益 10–20pp，正好可检测；这也是"先重试、后放置精度"的统计依据。
- 若用配对设计（同一初始状态、monitor on/off），方差会小很多；但正式榜单是不同提交之间的非配对比较，不能假设配对。离线/仿真 A/B 可以用配对，真机调试槽只能做方向性验证。

### 2.5 第一杠杆 vs 第二杠杆

| 杠杆 | 作用 | 预期 | 成本 | 可检测 | 本轮优先级 |
|---|---|---|---:|---|---|
| 重试/早停（PULSE） | 把失败变成"再试一次" | +10–20pp | 低–中 | 高 | **P0** |
| 前置可达/碰撞（USIM） | 挡掉终局不可行 | +3–8pp（终局） | 低 | 中 | **P0** |
| 候选选择（UAVS） | 在 K 个候选中选更稳的 | +3–8pp | 中 | 中 | P1 |
| 放置精度/步骤分（PGL/OPT/SVL） | tiebreak | +步骤分 | 中 | 低（除非并列） | P1/P2 |
| 数据规模/L2L | 提升第一次 | +? | 高 | 低 | P2（规则未确认） |

### 3.2 USIM：执行前可用性检查

**输入**：候选终局 EE 位姿 \(p_{ee}\in SE(3)\)（来自 PGL/OPT），当前关节 \(q\)，当前 pivot/腰，场景点云/物体框（可选）。

**输出**：
- `reachable`：IK 是否收敛（位置误差 <5mm、姿态误差 <3°）；
- `joint_margin`：最紧关节到限位的余量（归一化 0–1）；
- `collision_margin`：到自碰撞/桌面/物体/其他物体的最小有符号距离（cm）；
- `visibility`：目标在至少一个高相机 + 一个腕相机的视锥内（软分数）；
- `score`：加权后的可用性分数。

**实现**：
1. **离线可达图**：用 G1 URDF + 关节限位，在桌面工作空间 \((x,y,z,yaw)\) 上以 2–5cm 分辨率做 IK 网格；每个点存若干 IK 解与 margin。用 Pink/cuRobo/TRAC-IK 任一；CPU 即可。
2. **在线查询**：最近网格点 + 局部 IK 精化；<2ms/候选。
3. **碰撞**：机器人胶囊/网格自碰撞 + 桌面平面 + 物体 AABB/OBB；阈值 >1cm。
4. **pivot/腰调整**：若目标不可达，搜索 pivot/腰的小网格（±5–10°），返回最佳；`action.pivot` 的语义未完全公开，先在调试槽验证，不要大幅使用。
5. **兜底**：不依赖 Isaac Sim 的解析 IK + 胶囊碰撞；Isaac Sim 只用于离线建图/验证。这样即使规则不允许外部仿真，USIM 仍可用官方 URDF 运行。

**为什么不是运行时仿真**：Isaac Sim 单步/渲染太重，放进 `get_action` 会拉高 p99；我们只取它的**几何结果**（离线建图），运行时是查表/解析。

**失败处理**：
- 不可达 → 换候选（PGL 的下一个槽位/OPT 的下一个样本）；
- 会撞 → 抬高/后退/换抓取；
- 关节余量小 → 调腰/pivot 或换手；
- 都失败 → 回退到 VLA 的原始动作（不要卡死）。

### 3.3 PAM：执行中的本体可用性监测

**核心思想**：在成功数据上学习名义动力学 \(p(s_{t+1:t+H}\mid s_{t-k:t}, a_{t:t+T_a})\)；测试时，实际本体轨迹与预测的残差就是"动作-结果不一致"的证据。**不需要失败标签**。

**输入**：
- 本体历史：`left_arm[7]`, `right_arm[7]`, `left_gripper[1]`, `right_gripper[1]`, `lower_body[15]`（共 31 维；可加 EE 位姿 12 维，但 EE 可由 FK 得到，避免冗余）；
- 上一个 chunk 的动作：`left_arm[7]`, `right_arm[7]`, `left_gripper[1]`, `right_gripper[1]`, `pivot[7]`（共 23 维/步）；
- 可选：视觉 latent（只用于诊断，不用于残差，避免背景/光照干扰）。

**输出**：
- 异常分数 \(r_t\)（标量）；
- 失败概率 \(P_f\)（校准后）；
- 失败类型（抓空/滑落/卡住/碰撞/人为干扰/语义错误）与置信度；
- 预测的本体轨迹（用于 TTR/诊断）。

**结构**（建议）：
```
proprio history (H×31) ──► MLP(31→128) ──► GRU/Transformer(2层,256) ──┐
action chunk (T_a×23) ──► MLP(23→128) ──► action encoder ──────────────┼─► cross-attn ─► decoder ─► future proprio (T_a×31, mean+var)
                                                                                                                                  │
                                                                                                                                  ▼
                                                                                                                        residual / NLL
```
- 参数量 1–5M；延迟 <5ms（CPU/GPU 均可）。
- 预测视野 \(H_{pred}=T_a\) 或 \(2T_a\)；若太长，只预测前 8–16 步，减少误差累积。
- 训练：teacher forcing + 多步 rollout loss；方差用 Gaussian NLL；对残差做归一化（按关节/维度的名义标准差）。

**异常分数**：
\[
r_t = \frac{1}{H_{pred}}\sum_{\tau=1}^{H_{pred}} \left(s_{t+\tau}-\hat{s}_{t+\tau}\right)^\top \Sigma_{t+\tau}^{-1}\left(s_{t+\tau}-\hat{s}_{t+\tau}\right)
\]
或用对角近似/马氏距离；再做时间平滑（EMA）与滞后（避免单帧噪声）。

**校准**：
- 在成功留出集上算 \(r_t\) 的分布；取 \((1-\alpha)\) 分位为阈值 \(\tau_\alpha\)，\(\alpha=0.05\)（目标 FPR 5%）。
- 用 conformal prediction 给出边际覆盖保证；按任务/阶段分层校准（抓取/运输/放置的残差尺度不同）。
- 多频率校准：把 30fps 数据重采样到 10/15/20/30Hz，取保守分位；因为评测控制频率未知。
- 阈值不是固定的：TTR 可以用 \(P_f\)（校准后的尾概率）而不是硬阈值。

**诊断**（规则 + 小分类头）：
| 症状 | 抓空 | 滑落 | 卡住/碰撞 | 人为干扰 | 语义错误 |
|---|---|---|---|---|---|
| 夹爪闭合后开度 | 接近 0 | 提起后突降 | 正常 | 正常/被打开 | 正常 |
| 跟踪误差 | 抓取段高 | 运输段高 | 接触段高 | 局部尖峰 | 低 |
| EE 位置偏差 | 提起时向下 | 运输时向下 | 接触方向卡住 | 目标被移动 | 目标错 |
| 视觉谓词 | 无物体 | 物体掉落 | 物体未动 | 物体位移 | 物体/目标错 |
| PAM 残差 | 高 | 高 | 高 | 中–高 | **低** |

**关键设计原则**：
- **本体感知只进 PAM，不进动作主干**。GAP（[S37]）证明本体感知会在运动过渡段压制视觉；ContactGuard（[S36]）发现小数据下本体输入可能有害。动作策略保持视觉-语言主导。
- **PAM 不做语义判断**；语义错误交给 SSG 的视觉谓词。PAM 的失败类型里"语义错误"只作为"低残差 + 谓词失败"的排除项。
- **PAM 是同一 checkpoint 的辅助头**：共享 VLA 的视觉/语言 trunk 或独立小头；在模型卡中披露。不要起一个独立的第二模型服务。

**训练数据**：
- 只用官方成功演示（33k）训练名义动力学；**不用失败数据训练**（避免模型学会预测失败、降低残差）。
- 扰动数据（sim/合成）只用于**验证/校准/阈值选择**，不参与训练；可选：用少量扰动做对比学习，让名义流形更紧，但要小心。
- 数据划分：按 episode 划分 train/val/cal；按任务留出做跨任务泛化测试；按场景（背景/位置）留出做 OOD 测试。

**为什么可行**：
- 33k 成功轨迹 × 每任务 ~1k，足够学一个低维本体动力学；
- 动作是命令目标，跟踪误差可直接算；
- 夹爪开度是强信号；
- 文献一致：KIT 96.97% @50% execution（[S31]）、RAPT G1 50Hz（[S34]）、ProTracer onset（[S32]）、Foundational WM 1/20 参数 +3.8%（[S33]）。

### 3.4 UAVS：候选动作选择

**动机**：在终局放置/插入步，VLA 的多个候选（不同噪声/不同目标位姿）成功率差异大；用 USIM + PAM 先验选一个更"可用"的。

**候选生成**：
- K=2，仅用于 28 个放置类终局的最后一步；
- 候选 A：VLA 的均值/原始 chunk；候选 B：对终局 EE 位姿加小扰动（来自 OPT 的协方差）或换一个 PGL 槽位；
- 其他步骤 K=1；USIM 检查终局位姿，若不可行再采样一次（不增加 VLA 前向）。

**打分**：
\[
U(c)=w_p\hat{P}_{prog}(c)+w_r m_{reach}(c)+w_c m_{col}(c)-w_s\hat{r}(c)-w_j J(c)
\]
- \(\hat{P}_{prog}\)：SSG 谓词/进度预测（0–1）；
- \(m_{reach}\)：USIM 可达 margin（0–1）；
- \(m_{col}\)：碰撞 margin（0–1）；
- \(\hat{r}\)：PAM 对候选 chunk 的预测残差（归一化）；
- \(J\)：动作 jerk/平滑度（0–1）。
- 默认权重：0.35 / 0.25 / 0.20 / 0.15 / 0.05；在小验证集上调。

**选择**：取 \(U\) 最大；若两个候选的 \(U\) 差 <ε，选更平滑/更接近演示分布的那个（降低交互异常风险）。

**成本**：K=2 的 VLA 前向翻倍；只在终局步用，按 2–5 步任务平均开销约 **1.2–1.5×**（2 步 1.5×、3 步 1.33×、4 步 1.25×、5 步 1.2×）。若 p99 超预算，退回 K=1 + USIM 检查。

### 3.5 TTR：时间预算与重试调度

**在每个 chunk 边界**：
1. \(T_{rem}=180-t_{elapsed}\)；
2. 估计剩余任务时间 \(T_{task}\)：用演示中位时长 × 观测到的 slowdown \(s=t_{elapsed}/t_{demo\_expected}\)；
3. 从 PAM 得到 \(P_f\)；
4. 估计继续的期望成功率 \(E_{cont}=(1-P_f)+P_f r_{cont}\)；
5. 估计早停重试的期望 \(E_{retry}=r_{retry}\cdot\mathbb{1}[T_{rem}>T_{retry}+T_{task\_remaining}]\)；
6. 若 \(E_{retry}>E_{cont}+\delta\) 且时间够 → 早停/重试；若 \(P_f\) 高但时间不够 → 继续（last-ditch）或保守完成；若 \(P_f\) 在阈值附近且时间充足 → 主动探测（可选）。

**重试粒度**：
- 从**最后一个已验证的 SSG 步骤**重试，不从头开始；
- 2–3 步任务：允许 2 次；4–5 步任务：每步最多 1 次，总重试 ≤3；
- 重试前先做"恢复动作"：松开夹爪（若抓着）、后退 5cm、重新观测；不要在原位反复闭合。

**平滑 abort**：
- 减速到停（不是急停）→ 松开 → 后退 → 重规划；
- 避免在抓取力很大时硬拉；避免把物体甩出桌面；
- 记录 abort 的时延/jerk，纳入 Usability Card。

**主动探测**（可选，I19）：
- 当 \(P_f\) 在阈值附近、且时间充足时，执行一个小的"探针"动作（提起 2cm/轻推/旋转 5°），用结果消歧；
- 探针动作来自一个小库（<10 个），不训练新模型；
- 探针有风险（可能把物体弄掉），只在"不确定 + 时间够 + 物体在桌内"时用。

### 3.6 与 SSG/PGL/OPT/ICR/SVL 的接线

| 组件 | 输入 | 输出 | 在 PULSE 中的角色 |
|---|---|---|---|
| SSG | language + 当前 obs | 当前步 \(s\)、已验证步 \(\hat{s}\)、谓词 | TTR 的重试起点；语义失败检测 |
| PGL | language + 场景 | 候选放置槽位/锚点 | USIM/UAVS 的候选位姿 |
| OPT | 容器 + 演示库 | 释放位姿均值/协方差 | 候选采样先验；USIM 目标 |
| ICR | 当前步 + 检索库 | 上下文段 | 可选；延迟允许才开 |
| SVL | 释放后 obs | 稳定/谓词/位移 | post-flight；失败→nudge/regrasp |
| NRB | human_1/4 备注 | 干扰剧本 | PAM/TTR 的验证集；不是主训练 |

**SVL 升级**：第 7 轮的 SVL 是"释放后等稳定→nudge/regrasp"；本轮把它接到 PULSE 的 post-flight：
- 释放后 0.5–1.0 秒检查物体位移/谓词；
- 若位移 >阈值或谓词失败 → 判定"放置失败"；
- 若 PAM 也高 → 重试当前步；若 PAM 低但谓词失败 → 语义/视觉问题，走 SSG 重规划；
- 若稳定且谓词通过 → 标记该步 verified，进入下一步。

### 3.7 伪代码

```python
class PulsePolicy:
    def __init__(self, vla, pam, usim, ssg, pgl, opt, ttr, svl):
        self.vla, self.pam, self.usim = vla, pam, usim
        self.ssg, self.pgl, self.opt = ssg, pgl, opt
        self.ttr, self.svl = ttr, svl
        self.history = []
        self.last_chunk = None
        self.last_pred = None
        self.retry_count = 0

    def reset(self):
        self.history.clear()
        self.last_chunk = None
        self.last_pred = None
        self.retry_count = 0
        self.ssg.reset()
        self.pam.reset()

    def get_action(self, obs):
        self.history.append(parse_proprio(obs))
        # 1) PAM: compare previous prediction with actual
        if self.last_pred is not None:
            r, p_f, failure_type = self.pam.score(self.last_pred, self.history[-1])
            self.ssg.update(obs, failure_type)
            # 2) TTR: continue / abort / retry / probe
            decision = self.ttr.decide(
                t_elapsed=obs.t,
                p_fail=p_f,
                step=self.ssg.current_step,
                verified_step=self.ssg.verified_step,
                retry_count=self.retry_count,
            )
            if decision.abort:
                self.retry_count += 1
                self.ssg.rollback_to(decision.retry_step)
                return self.make_recovery_chunk(obs, decision)
        # 3) SSG: if current step verified, advance; if final verified, hold
        if self.ssg.step_verified(obs):
            self.ssg.advance()
        # 4) candidate generation
        candidates = self.vla.propose(obs, k=2 if self.ssg.is_final_placement() else 1)
        # 5) USIM + PAM prior + UAVS selection
        scored = []
        for c in candidates:
            m = self.usim.check(c.terminal_ee_pose, obs)
            r_hat = self.pam.predict_residual(self.history[-H:], c.actions)
            u = self.uavs_score(c, m, r_hat, obs)
            scored.append((u, c))
        chunk = max(scored, key=lambda x: x[0])[1]
        # 6) stash prediction for next boundary
        self.last_chunk = chunk
        self.last_pred = self.pam.predict(self.history[-H:], chunk.actions)
        return chunk.to_api()
```

```python
def train_pam(demos):
    # demos: (proprio[t-H:t], action[t:t+T], proprio[t+1:t+1+T])
    model = PAM()
    for batch in demos:
        pred = model(batch.proprio_hist, batch.actions)
        loss = gaussian_nll(pred, batch.future_proprio) + smoothness(pred)
        loss.backward(); opt.step()
    # calibration: only nominal held-out
    scores = [model.score(b) for b in cal_loader]
    tau = quantile(scores, 1 - alpha)
    return model, tau
```

## 4. 数据引擎

### 4.1 名义成功数据（主训练集）
- 33k 官方演示；每任务 ~1k；30fps；按 episode 成功过滤（若数据含失败片段）。
- PAM 的输入/输出都用官方字段；动作是命令目标（`action.left_arm/right_arm` 等），不是仅下一帧状态。
- 预处理：
  - 关节角归一化到任务内均值/标准差；
  - 夹爪开度归一化到 [0,1]；
  - 伪速度 \(v_t=(q_t-q_{t-k})/k\)，k=2–4；不除以未知的 \(\Delta t\)；
  - 动作 chunk 与本体历史对齐；episode 边界 pad/ mask；
  - 多频率重采样（10/15/20/30Hz）做阈值校准。
- 划分：按 episode 80/10/10；按任务留出 4 个做跨任务；按背景/位置留出做 OOD。

### 4.2 仿真扰动数据（只做验证/校准）
在官方 sim 的成功轨迹上随机化：
- 物体质量 ×0.5–2、摩擦 ×0.5–1.5；
- PD 增益 ×0.7–1.3、控制时延 0–50ms；
- 外力脉冲（模拟碰撞/人为推）；
- 夹爪摩擦/开度偏差；
- 初始物体位姿偏移 1–5cm。
生成"名义 vs 扰动"成对序列；PAM 在名义上训练，在扰动上测 TPR/FPR。**不把扰动放进训练集**（避免模型学会预测扰动、降低残差）。

### 4.3 官方 human 剧本（验证/测试）
- `human_1_note` / `human_4_note` 是 1-DOF 平移/撤销剧本；用它们做**真实干扰**的验证：
  - T27：叠第二个碗后拿走 → PAM 应检测"物体消失/谓词回退"；
  - T10：抓插头前移动 / 拔起 → PAM 应检测跟踪误差/位置偏差；
  - T19：拉上后再拉开 → SSG 谓词回退 + PAM 局部尖峰；
  - T24：把食物放回传送带起点 → 视觉谓词 + 本体残差；
  - T17：笔盒合上后手动打开 → 谓词回退。
- 这些剧本同时是 NRB（恢复库）的测试用例；不把它们当主训练数据（编号含义未核实）。

### 4.4 标签与划分
- PAM 训练：只用成功（名义）；无失败标签。
- PAM 验证：
  - 名义留出集：FPR；
  - sim 扰动：TPR；
  - human 剧本/真机调试：真实 TPR/延迟。
- SSG 谓词：用演示的步骤边界 + 视觉标签训练（第 7 轮 TLE 管线）；PAM 不需要步骤标签。
- 数据泄漏：按 episode/任务/场景划分；不要把同一 episode 的相邻窗口分到 train/cal。

### 4.5 规模与算力
- 名义数据：33k episodes × 平均 ~180 帧 ≈ 6M 帧；PAM 只用低维本体，存储 <10GB。
- 训练：单卡 A100/H100 数小时–1 天（1–5M 参数，小数据）。
- 仿真扰动：每任务 100–500 条 × 8 个代表任务 ≈ 0.8k–4k 条；CPU/单卡 sim 数小时–1 天。
- 真机：调试槽 2–4 次；计分跑 1–2 次。

## 5. 训练配方

### 5.1 PAM 结构
- 输入维：31（本体）+ 23（动作）/步；H=8–16，T_a=8–16。
- Encoder：MLP 31→128，动作 MLP 23→128；GRU 2 层 256 或 Transformer 2 层 4 头。
- Decoder：MLP 256→31×H_pred（均值+方差），或逐帧输出。
- 参数量：1–5M；延迟 <5ms。
- 可选：与 VLA trunk 共享视觉 latent（仅诊断），但不把本体输入动作主干。

### 5.2 损失
\[
\mathcal{L} = \underbrace{\sum_{\tau}\frac{(s_{t+\tau}-\hat{s}_{t+\tau})^2}{2\sigma_{t+\tau}^2}+\frac{1}{2}\log\sigma_{t+\tau}^2}_{\text{Gaussian NLL}}
+ \lambda_1 \|\hat{s}_{t+\tau}-\hat{s}_{t+\tau-1}\|_1
+ \lambda_2 \mathcal{L}_{contrast}
\]
- 平滑项 \(\lambda_1=0.01\)–0.1；
- 对比项（可选）：名义 vs 扰动窗口的残差分离；\(\lambda_2\) 小，避免过拟合扰动分布；
- 多步 rollout：先 teacher forcing，后 2–3 步自由 rollout，减少暴露偏差。

### 5.3 课程
1. 单任务名义动力学（HangCup/StackBowls）→ 验证能拟合；
2. 多任务联合（32 任务）→ 任务 embedding/one-hot；
3. 多频率重采样 → 阈值鲁棒；
4. 扰动验证 → 调阈值/结构；
5. 真机调试槽 → 校准真实时延/噪声；
6. 全量计分跑 → 只调 TTR 阈值，不重训 PAM。

### 5.4 超参（起点）
| 项 | 值 |
|---|---|
| H（历史） | 8–16 帧 |
| H_pred | 8–16 帧 |
| T_a | 8（若基线用 16，则 16） |
| hidden | 256 |
| layers | 2 |
| batch | 256 窗口 |
| lr | 1e-3（AdamW） |
| epochs | 20–50（早停） |
| α（FPR） | 0.05（调试槽后可 0.10） |
| EMA | 0.9–0.98 |
| 阈值 | 分层 conformal 分位 |

### 5.5 算力
- PAM：单卡 1 天以内；
- USIM 可达图：CPU 数小时（或 GPU 并行）；
- 仿真扰动：单卡/CPU 1 天；
- 总计：<3 天单卡，主要成本在 VLA 基线和真机调试。

## 6. 评测协议

### 6.1 Usability Card（本轮新增的过程产物）
每次提交/调试跑生成一张卡，包含：

| 维度 | 指标 | 目标 |
|---|---|---|
| pre-flight | IK 成功率、碰撞 margin、关节 margin | IK ≥95%；margin >1cm |
| in-flight | TPR@FPR=5%、检测延迟、onset 误差 | TPR ≥80%；延迟 ≤1–2 chunk |
| post-flight | settle 位移、谓词通过率、步骤分 | 位移 <5mm；谓词 ≥90% |
| system | 时延 p50/p99、jerk、chunk 规律性 | p99 <基线+20ms；jerk <演示 95 分位 |
| outcome | 成功率、步骤分、time-to-success | 成功率 +10pp（目标） |
| interaction | 重试次数、abort 平滑度、异常日志 | 总重试 ≤3/局；无硬停 |

这张卡同时服务 README §6 的"交互质量/结果可信度"：我们把官方会看的东西**主动量化**，而不是等它来查。

### 6.2 离线
- PAM：留出 episode 的 FPR；sim 扰动的 TPR/延迟；按任务/阶段分层。
- USIM：候选位姿的 IK 成功率/碰撞率；与真机可达性的一致性（调试槽）。
- UAVS：离线重放候选打分与真实成功/失败的相关性（AUC/NDCG）。
- SVL：释放后位移/谓词与人工标注的一致性。

### 6.3 仿真回放
- 用官方 sim 回放成功轨迹 + 扰动；测 PAM 检测（TPR/FPR/延迟）。
- 不做"仿真任务成功率"的承诺（场景不是评测孪生）；只做**监测器**的验证。
- 如果规则不允许 sim，改用解析扰动/真实数据留出；sim 只作开发工具。

### 6.4 真机调试槽
- 任务选择：T27（StackBowls，human_4 拿走第二个碗）→ T10（PlugCharger，插入/拔出）→ T19（ZipUp，拉上后拉开）。
- 每次调试跑：
  - 先跑 5–10 次基线（无 PULSE），记录失败类型/时间；
  - 再跑 5–10 次 PULSE，记录检测/重试/恢复；
  - 对比：检测延迟、误报、重试成功率、总时长、jerk。
- 判定：TPR ≥60%、FPR ≤10%、重试成功率 ≥20% → 进入下一阶段；否则回退/调阈值。
- 次数未知；每个大版本最多 1 槽，优先用在"最能证伪"的任务。

### 6.5 计分跑
- 全 32 任务 × 10 次；目标不是"一次就完美"，而是拿到真实的失败分布/时延/步骤分。
- 第一次计分跑：PULSE 全开，但 TTR 保守（只在高置信 + 时间充足时重试）。
- 第二次：根据第一次的失败类型调阈值/重试粒度。
- 记录：每任务成功率、步骤分、平均时长、重试次数、检测类型；用于 Usability Card 和下一轮。

### 6.6 发布门控
- PAM：TPR ≥80% @ FPR ≤5%（留出扰动）；调试槽 TPR ≥60% @ FPR ≤10%。
- USIM：IK ≥95%、碰撞 margin >1cm；调试槽无因 USIM 误判导致的失败。
- UAVS：离线首试成功率 +5pp；若没有，关 K=2。
- TTR：调试槽重试成功率 ≥20%、总时长不超 180s、无硬停。
- 系统：p99 <基线+20ms；jerk <演示 95 分位；无异常长尾。
- 合规：PAM 同一 checkpoint；模型卡披露；外部数据默认 OFF。

## 7. 实验矩阵与消融

### 7.1 主实验
| ID | 配置 | 目的 | 预期 |
|---|---|---|---|
| E0 | 基线 VLA，固定 T_a，无 PULSE | 基线 | 30% 左右（弱先验） |
| E1 | E0 + PAM（只监测，不重试） | 检测指标 | TPR/FPR/延迟 |
| E2 | E1 + USIM（终局检查） | 前置可用性 | 终局失败 −10–20% |
| E3 | E2 + UAVS（K=2 终局） | 候选选择 | 首试 +3–8pp |
| E4 | E3 + TTR（早停/重试） | 主收益 | +10–20pp |
| E5 | E4 + 主动探测 | 消歧 | 检测 +/误报 − |
| E6 | E5 + sim 扰动训练/校准 | 鲁棒性 | OOD 检测 + |

### 7.2 消融
- K=1 vs K=2；只终局 vs 全步；
- PAM 输入：仅本体 vs 本体+EE vs 本体+视觉 latent；
- PAM 训练：名义 only vs 名义+少量扰动；
- 阈值：固定 vs conformal vs 分层 conformal；
- TTR：早停 vs 不早停；重试从头 vs 从失败步；
- USIM：Isaac Sim 建图 vs 解析 IK；有无 pivot/腰调整；
- 检测频率：chunk 边界 vs 子采样（如果接口允许）；
- 动作空间：joint vs ee（对 PAM/USIM 的影响）；
- 图像分辨率：480×640 vs 240×320（对时延/成功率）。

### 7.3 诊断矩阵
| 失败类型 | 期望检测信号 | 期望恢复 | 若检测不到 |
|---|---|---|---|
| 抓空 | 夹爪开度≈0 + 跟踪误差 | 重抓 | 检查夹爪标定/视觉 |
| 滑落 | 开度突降 + EE 下偏 | 重抓/降低加速度 | 检查摩擦/速度 |
| 卡住/碰撞 | 跟踪误差 + EE 速度≈0 | 后退/换路径 | 检查 USIM/碰撞模型 |
| 插入失败 | 位置误差 + 接触后不动 | 微调/重试 | 检查力代理 |
| 人为干扰 | 物体位移 + 残差 | 重新观测/重规划 | 检查 SSG 谓词 |
| 语义错误 | 谓词失败 + 残差低 | 重规划 | 检查视觉 grounding |

## 8. 创新点清单（持续迭代；动机/差异/可行性/资源/步骤/风险/状态）

> 状态：押注=本轮主线；保留=沿用；升级=旧点改造；降级=保留但非主回路；砍=不做。

### I1 PULSE 自可用性回路（新增，押注）
- **动机**：成功率优先 + 180s + 30% 单次 → 重试是第一性杠杆；可用性评估应从"离线报告"变成"运行时闸门"。
- **差异**：现有 VLA 只输出动作；PULSE 在 chunk 边界做"前置几何检查 + 本体残差监测 + 候选选择 + 时间调度"，不改变动作主干。
- **可行性**：USIM 用官方 URDF/Isaac 资产；PAM 用 33k 成功数据；TTR 是规则；全部可在单卡 + 调试槽验证。
- **资源**：PULSE 增量 1 张 A100/H100；VLA 基线沿用第 7 轮算力；33k 演示（已有）；2–4 次调试槽；1–2 次计分跑。
- **步骤**：USIM 建图 → PAM v0 → UAVS/TTR → 调试槽 → 计分跑。
- **风险**：误报/时间不够/合规；用 conformal + 保守 TTR + 同一 checkpoint 缓解。
- **状态**：押注。

### I2 PAM 本体动作-结果监测（新增，押注）
- **动机**：API 无时间戳/力矩，但有关节/夹爪；成功数据足够学名义动力学；文献支持本体感知早期检测。
- **差异**：只用成功数据训练，不需要失败标签；残差 + conformal 校准；本体只进监测头，不进动作主干（避免 GAP/ContactGuard 的负迁移）。
- **可行性**：1–5M 参数、<5ms；数据字段齐全；30fps → 多频率校准。
- **资源**：单卡 1 天；无额外标注。
- **步骤**：数据管道 → 单任务拟合 → 多任务 → 多频率 → 扰动验证 → 调试槽。
- **风险**：语义错误测不到；小数据/域差导致误报；用 SSG 谓词 + 分层阈值缓解。
- **状态**：押注。

### I3 USIM 前置可达/碰撞检查（新增，P0 支撑）
- **动机**：终局放置是闸门；不可达/撞桌的候选应在执行前挡掉；Isaac Sim 的几何能力正好匹配。
- **差异**：不做数字孪生/像素训练；只取 IK/碰撞/限位 margin；运行时查表，不跑 sim。
- **可行性**：官方 URDF + 关节限位；Pink/cuRobo/解析 IK；<2ms/候选；可无 sim 兜底。
- **资源**：CPU 数小时建图；无额外数据。
- **步骤**：URDF → 可达图 → 碰撞体 → 查询 → 与调试槽一致性。
- **风险**：`action.pivot` 语义未公开；相机标定未知；用保守 margin + 调试槽校准。
- **状态**：P0 支撑。

### I4 TTR 时间预算重试（新增，P0 支撑）
- **动机**：180s 够 2–3 次；但失败可观测时间不同；需要"继续/早停/重试/探测"的调度。
- **差异**：不是简单"失败就重试"；用剩余时间、失败概率、重试成功率、失败类型做期望值决策；从已验证步骤重试。
- **可行性**：规则 + 少量超参；可在调试槽调。
- **资源**：无额外算力；需要真实时延/失败类型。
- **步骤**：时间估计 → 期望值规则 → 平滑 abort → 重试粒度 → 调试槽。
- **风险**：误判导致时间浪费/硬停；用保守阈值 + 平滑 abort + 总重试上限。
- **状态**：P0 支撑。

### I5 Usability Card（新增，过程/评测）
- **动机**：官方记录交互质量/时延/动作规律性；我们需要主动量化，而不是被动被查。
- **差异**：把"可用性"拆成 pre/in/post/system/outcome 五组指标，每次提交生成一张卡。
- **可行性**：全部可从日志/评测结果计算；无需新模型。
- **资源**：日志管道；1 人周。
- **步骤**：定义指标 → 日志埋点 → 自动生成 → 发布门控。
- **风险**：指标太多/噪声；用少而硬的指标 + 置信区间。
- **状态**：P0 过程。

### I6 SVL post-flight 稳定/谓词复核（升级，P1）
- **动机**：释放后失败（掉落/弹跳/未到位）是终局闸门的最后一厘米；PAM 只看本体，SVL 看结果。
- **差异**：从"落点闭环"升级为 PULSE 的 post-flight；与 PAM 残差联合判定。
- **可行性**：腕部相机 + 谓词；0.5–1s 检查；180s 够。
- **资源**：无新数据；谓词头复用 SSG。
- **步骤**：稳定检测 → 位移阈值 → nudge/regrasp → 与 TTR 接线。
- **风险**：耗时/误判；双阈值 + 长任务限 1 次。
- **状态**：P1。

### I7 SSG 步骤状态机（降级，支撑）
- **动机**：TTR 需要"当前步/已验证步"；语义失败需要谓词。
- **差异**：从"主押注"降为"状态机 + 谓词"；不追求每步完美。
- **可行性**：32×5 复述匹配；谓词头用演示标签。
- **资源**：CPU；1 人周。
- **步骤**：解析 info.json → 图 → 谓词 → 回退/推进。
- **风险**：谓词噪声 → 用演示统计校准；语言未覆盖 → 嵌入兜底。
- **状态**：降级。

### I8 PGL 放置目标阶梯（保留，支撑）
- **动机**：USIM/UAVS 需要候选 6D 位姿；Spa-Bench/AnySlot 证明显式视觉目标有效。
- **差异**：保留第 7 轮的三级"语言→槽位→锚点→位姿"；本轮只作为候选源。
- **可行性**：已有管线；渲染/投影确定性。
- **资源**：检测器/SAM（许可核对）；无重训最小版。
- **步骤**：槽位 → 锚点 → 位姿 → USIM 查询。
- **风险**：锚点域差；双层一致性检查。
- **状态**：保留。

### I9 OPT 放置位姿迁移（保留，支撑）
- **动机**：演示释放位姿是现成先验；少样本迁移比从零回归稳。
- **差异**：迁移容器系相对位姿统计 + 协方差；为 UAVS 提供候选分布。
- **可行性**：EE 位姿 + 容器检测；已有同构证据。
- **资源**：容器 6D 位姿；8×H100 数天建库（可缩减）。
- **步骤**：TLE → H_i → 检索 K → 候选。
- **风险**：透明/布料容器失效 → 回退 PGL/ICR。
- **状态**：保留。

### I10 ICR 检索上下文（降级，可选）
- **动机**：33k 是现成少样本库；检索式 VLA 有 +17–21pp 证据。
- **差异**：键=关系+运动；相位用 SSG 对齐；缓存控延迟。
- **可行性**：缓存 <1GB；HNSW；p99 可控。
- **资源**：8×H100 1–2 天；缓存。
- **步骤**：切段 → 建键 → 缓存 → 训练注入 → 压测。
- **风险**：延迟 p99 超标 → 关；透明任务键失效 → 回退。
- **状态**：降级。

### I11 NRB 官方备注恢复（升级为验证集）
- **动机**：human_1/4 是官方干扰剧本；可用于 PAM/TTR 的真实验证。
- **差异**：从"恢复库"转为"测试/训练用例"；不把编号含义当已知。
- **可行性**：1-DOF 平移/撤销，易合成/回放。
- **资源**：ACP/2.5D 管线；少量。
- **步骤**：备注表 → 场景脚本 → 验证 → 恢复对。
- **风险**：编号含义未核实 → 同时覆盖通用扰动。
- **状态**：升级为验证。

### I12 GPR-VLA 主干 + WLA 底座（保留）
- 唯一学习型动作模型；PAM 是辅助头；WLA Apache-2.0、单卡可微调。
- 风险：底座微调不足 → LoRA 分级。

### I13 TLE/ACP/GF 数据引擎（保留，修剪）
- 只服务放置/关键步；合成负迁移 → 软权重 + 真实混采。

### I14 AH-TP / Endurance Governor / Compliance Compiler（保留）

### I15 TCLB（降级）
- 离线相对比较台；不再承诺真机校准子集为主回路。

### I16 FLEET 工程检查单（降级｜第 6 轮遗产）
- N 端口连续 8765、每端口独立、状态隔离、延迟弹性、健康检查；工程保留，不做研究贡献。

### I17 DebugLoop（保留，关键）
- 不计分单任务调试槽；T27→T10→T19；每版本最多 1 槽；记录 Usability Card。

### I18 Chunk/时延校准（新增，工程）

## 12. 开放问题

1. **控制频率/时序**：评测端多久调用一次 `get_action`？chunk 内是否严格开环？`get_action` 的周期是否等于 T_a × 控制周期？
2. **chunk 语义**：`action_chunk_size` 固定后，能否返回比 T_a 短的 chunk？评测端是否 pad/截断？
3. **`action.pivot`**：7 维的物理含义/单位/限幅？是底座速度、腰目标，还是组合？能否用于大幅调整？
4. **`lower_body` 排列**：15 维里哪 3 维是腰？与 `waist_state_joint` 的对应关系？
5. **外部数据/仿真**：官方是否允许自采/实验室数据、Isaac Sim 生成数据、预训练权重？规则公开部分未写。
6. **单模型边界**：PAM 辅助头、USIM 确定性代码、检索库是否需要/如何披露？审计标准？
7. **步骤分聚合**：逐 episode 平均、取最好、还是按步骤完成率？影响 tiebreak 策略。
8. **调试槽**：可用次数/成本/是否随机化泛化条件？能否指定 T27/T10/T19？
9. **备注编号**：human_1/human_4/unseen_object_3 是轴编号还是试次编号？评测是否就在这些剧本里采样？
10. **真实榜单**：何时发布？演示数据是否会被真实数据替换？真实失败分布是什么？
11. **N 台机器人**：并发/端口/时延上限？是否影响 chunk 周期？
12. **安全/交互质量**：abort/retry 是否会被判为异常？硬停/急停是否触发安全终止？
