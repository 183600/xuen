# 第 61 轮（承接第 60 轮「场景感知闭环」IP-153~160；灵感循环第 1 轮；本轮灵感：「专利布局」×「伦理与合规」）

> 第 60 轮的 SGEC 已把「场景→意图→约束→阻抗→执行→证据」闭成环，技术密度很高，但暴露了**两个非技术性、却决定项目能否成立**的盲区：
> 1. **有创新、无布局**：IP-145~160 共 16 个「创新点」仅停留在方法描述，没有权利要求树、没有现有技术检索、没有「申请 vs 防御性公开」的时间策略。在 UniBot 这类公开竞赛/论文场景中，**先公开 ≈ 丧失新颖性**；若只申请核心而不布外围，竞争对手可用一个 trivial 变体绕开。技术领先 ≠ 可防御。
> 2. **有安全、无合规**：第 59~60 轮解决的是「执行不出事」，但「不出事」只是安全（safety），不等于合规（compliance）与伦理（ethics）。合规要求的是**可证明地满足外部规范**（ISO/TS 15066 功率力限制、ISO 13482 个人护理、EU AI Act 高风险系统、GDPR/个保法数据最小化）；伦理要求的是**可问责、可解释、可干预、不歧视**。「执行层自信地违反规范」比「执行层失败」更危险，因为它会产出**看似合规的证据**。

## 0. 直觉与动机

**灵感 1（专利布局 → 从「想法清单」到「权利要求覆盖」）**
直觉：专利布局不是给想法起名字，而是**用最少的独立权利要求覆盖最多的可实施空间，同时让规避设计付出高代价**。把每个机制 m_i 看成被一组权利要求 f_j「覆盖」的元素，布局就是选一个子集 F′，使「覆盖价值 / 申请成本」最大，并显式扣除「现有技术命中风险 ρ」与「提前公开导致的新颖性损失 δ」。关键洞见：**第 60 轮的 16 个 IP 不是 16 份专利，而是一张覆盖矩阵**——真正该独占的是「约束编译 + 证据链 + 意图锁定」的组合，而不是每个单点。

**灵感 2（伦理与合规 → 合规即证据、证据即约束）**
直觉：合规检查最容易退化成「事后写报告」，而报告可以造假。真正的合规应当**双重嵌入**：
- **事前**：把法条翻译成执行约束（如 F ≤ F_max），让「违规在物理上不可达」——合规构造（Compliance-by-Construction）；
- **事后**：每个合规相关动作自动沉淀可验证证据，形成责任链。
关键洞见：**合规要求 r 必须同时拥有「预防性约束 g_r」与「可审计证据 e_r」两副面孔**，二者不可分离、缺一即失效。

**灵感 3（隐私 vs 审计的张力 → 可验证但不泄露）**
直觉：证据越完整越可审计，但遥测、视频、力曲线越完整越侵犯隐私（GDPR/个人信息保护法）。解法不是二选一，而是**只证明「约束成立」而不暴露「原始数据」**：用零知识证明把「证据」升级为「可验证声明」，用差分隐私控制统计披露。关键洞见：**审计力与隐私不是零和，只要把「证明」与「数据」解耦**。

**灵感 4（三灵感合流 → 合规-证据-专利三位一体 CEPT）**
直觉：同一个技术内核有三重身份——**技术机制（可运行）、合规证据（可审计）、专利权利要求（可主张）**。把三者绑定：谁想复制机制，既可能侵权（专利面），又必须承担同样的合规证据义务（合规面）。专利是「法律护城河」，合规证据是「信任护城河」，机制是「技术护城河」。

**灵感 5（PCE-C → 合规预算）**
直觉：合规不是免费的：审计要算力、解释要时延、人工接管要等待、法律风险要留余量。把 B_audit/B_explain/B_oversight/B_legal 纳入 PCE，合规预算耗尽时**自动降级到更保守、更可审计的行为**，而不是「假装合规」。

## 1. 形式化定义（增量：定义 161–168）

**定义 161（合规需求格 CRL：Compliance Requirement Lattice）** 合规规范 C = (R, ⪯, Φ, W, τ_audit)。其中：
- **需求集**：R = {r₁,...,r_m}，每条 r 对应一条法条/标准条款（如「接触力 ≤ F_max」「对外发布数据满足最小必要」「高风险动作须人工授权」）
- **细化偏序**：r₁ ⪯ r₂ 表示「满足 r₁ 蕴含满足 r₂」（r₁ 更严）。格结构支持**组合式审计**：只需验证极小元集合 min(R)
- **形式谓词**：Φ = {φ_r}，φ_r: E → {0,1} 作用于证据轨迹 E
- **证据抽取**：W：τ_trace → E，把执行轨迹映射为可审计证据
- **合规判定**：Compliant(C, τ) ⟺ ∀r∈R: φ_r(W(τ)) = 1
- **要求**：r₁ ⪯ r₂ ⇒ (φ_{r₁} ⇒ φ_{r₂})（**单调可靠性**，否则格结构不能用于剪枝）

**定义 162（合规构造编译 CbC：Compliance-by-Construction）** 编译器 Ξ: r ↦ (g_r, o_r, e_r, π_r)，满足：
- **守卫 g_r**：硬执行约束，注入 ERTC 契约与 EEIS 阻抗安全域（如 g_force: F_contact ≤ F_max）
- **软目标 o_r**：进入 CLEP 代价函数的惩罚项（如接近 F_max 时提高刚度阻尼）
- **证据义务 e_r**：执行时必须记录的证据字段与哈希
- **证明规格 π_r**：若启用 PVE，则给出 φ_r 的算术电路表示
- **编译可靠性（核心）**：任意执行 τ，若 (i) τ ⊨ g_r，(ii) τ 产生 e_r，则 φ_r(W(τ)) = 1。即 `g_r ∧ e_r ⇒ φ_r`
- **不可静默丢弃**：若 C_comp = ∩_r g_r 与 C_safe 交集为空，**禁止**自动放宽合规约束，必须升级人工（否则系统会为了「能跑」而静默违规）

**定义 163（伦理风险与对齐门 EAR：Ethical Alignment Router）** 伦理风险向量 E = (E_safety, E_privacy, E_autonomy, E_fairness, E_transparency, E_accountability) ∈ [0,1]⁶：
- **对齐分**：A = 1 − Σ_k w_k E_k，Σw_k = 1
- **三档门控**：
  - A ≥ θ_hi → 自主执行
  - θ_lo ≤ A < θ_hi → **人在环授权**：需在 τ_over 内获得人工签名，否则保持/降级
  - A < θ_lo → 拒绝/急停（refuse）
- **公平性**：E_fairness = max_g |Perf(g) − Perf(avg)|，跨场景/用户群体性能差异
- **自主性**：E_autonomy 由「未经同意的覆盖/越权操作次数」度量

**定义 164（决策责任链 DAC：Decision Accountability Chain）** 每个实质性决策 d 的溯源记录：
```
P(d) = (time, inputs_hash, model_ver, K_safe, C_comp, E,
        human_auth_sig, prev_hash, h = H(P(d)∖h))
```
- **哈希链**：h(d_i) 链接 prev_hash(d_{i−1})，任一环被篡改则后续全部失效
- **责任函数**：Resp(d) = Human 若存在有效 human_auth_sig；Operator 若 oversight 超时未响应；System 若在自主阈值内且无人工介入
- **可重建性**：给定 P(d_{1..n}) 与签名公钥，审计者可在不信任边缘节点的情况下复算合规判定

**定义 165（隐私可验证证据 PVE：Privacy-preserving Verifiable Evidence）** 证据发布算子：
- **差分隐私发布**：M_ε(E)，满足 ε-DP；用于统计型证据（分布、成功率）
- **零知识证明**：π = Prove(φ_r, E)，Verifier 以 V(φ_r, π) = 1 确认「φ_r(E) 成立」而不获得 E
- **同意令牌**：T_consent = (purpose, scope, expiry, subject_sig)；证据只能用于 scope 内目的（目的限定）
- **可审计性守恒**：若 φ_r 可由 π 验证，则审计准确率不随 ε 增大而下降（统计证据单独受 ε 影响）
- **披露预算**：发布证据消耗隐私预算 ε_total，超限只能发布 ZK 声明而不发布原始统计

**定义 166（合规预算 PCE-C：Compliance-Augmented PCE）** B_comp = (B_audit, B_explain, B_oversight, B_legal)：
- **B_audit**：审计算力/ZK 证明生成预算
- **B_explain**：解释生成时延预算（τ_explain）
- **B_oversight**：人工接管等待预算（τ_over 次数与总时长）
- **B_legal**：法律风险余量（未决 FTO/合规灰区的可承受暴露）
- **VOI 扩展**：`voi_cept(π) = VOI_meta_pessimistic(π) − cost_cog(π) − cost_comp(π) − cost_fin(π)`，其中 cost_fin 为专利/诉讼/罚款期望成本
- **降级阶梯**：完整审计 → 抽样审计 + ZK → 本地保守闭环 + 显式「未完全审计」标记（never silent）

**定义 167（专利布局映射 PLM：Patent Layout Mapper）** 给定机制集 M = {m_i}、候选专利族 F = {f_j}：
- **覆盖矩阵** A ∈ {0,1}^{|M|×|F|}，A_ij = 1 表示权利要求族 f_j 覆盖机制 m_i
- **参数**：机制价值 v_i、申请成本 c_j、现有技术命中风险 ρ_j、提前公开损失 δ_i
- **目标**（期望可防御性最大化）：
```
max_{x∈{0,1}^|F|}  Σ_i v_i·(1−δ_i)·[1 − Π_j (1 − A_ij·x_j)]·(1 − ρ̄(x)) − Σ_j c_j·x_j
s.t.  Σ_j c_j·x_j ≤ B_patent
```
- **覆盖函数次模** ⇒ 贪心达 (1−1/e) 近似；|F| 小可用 ILP 精确求解
- **三分决策**：每个机制选 File（核心、ρ 低）/ Defensive-Publish（ρ 高、防御他人抢占）/ Standard-Contribute（想成为标准必要专利 SEP，走 FRAND）
- **权利要求锚点**：为每个族抽取「最窄但最难绕开」的独立权利要求（claim anchor），作为 FTO 与规避分析的单位

**定义 168（合规-专利对偶与 FTO：CE-Duality & Freedom-to-Operate）** 
- **对偶映射**：每个机制 m 同时拥有权利要求集 Claim(m) 与证据义务 Ev(m)，耦合度 κ(m) ∈ [0,1]；κ 越高，复制机制越难同时避开「侵权」与「合规举证」双重成本
- **FTO 规避距离**：对阻断性专利族 f_block，`d_avoid(m, f_block) = 1 − max_{claim∈f_block} match(claim, m)`，match 为权利要求要素匹配率
- **规避阶梯**：R1 参数规避（改阈值）→ R2 架构规避（换拓扑）→ R3 功能规避（换原理）；R1 通常不足以绕开独立权利要求
- **部署闸门**：若 `d_avoid < d_min`，禁止部署该机制，必须先重新设计或取得许可（license）

### IP-161 CRL（合规需求格构建与判定）

```python
class ComplianceRequirementLattice:
    def __init__(self):
        self.requirements = {}   # id -> (predicate, refines, standard_ref)
        self.min_elements = set()
    def add(self, rid, predicate, refines=(), std_ref=""):
        self.requirements[rid] = (predicate, set(refines), std_ref)
        self.min_elements.add(rid)
        for r2 in refines:            # r1 ⪯ r2: r2 被更严者支配
            self.min_elements.discard(r2)
    def compliant(self, evidence):
        return all(self.requirements[r][0](evidence) for r in self.min_elements)
    def audit_report(self, evidence):
        return {r: bool(self.requirements[r][0](evidence))
                for r in self.requirements}
```

### IP-162 CbC（合规构造编译器）

```python
class ComplianceCompiler:
    def __init__(self, ertc, eeis):
        self.ertc, self.eeis = ertc, eeis
    def compile(self, lattice):
        guards, obligations, proofs = [], [], []
        for rid, (phi, _, std) in lattice.requirements.items():
            g_r = self._derive_guard(rid, phi)      # 例: F<=Fmax -> K_safe 上界
            e_r = self._derive_evidence(rid, phi)   # 例: 记录 F_peak, 时间戳, hash
            guards.append(g_r); obligations.append(e_r)
            proofs.append(self._circuit(phi))
        C_comp = self.ertc.intersect(guards)
        if self.ertc.meet(C_comp, self.eeis.K_safe) is None:
            return ESCALATE_HUMAN          # 禁止静默放宽合规约束
        return CompiledCompliance(C_comp, obligations, proofs)
```

### IP-163 EAR（伦理对齐门）

```python
class EthicalAlignmentGate:
    def __init__(self, w, theta_hi=0.85, theta_lo=0.55, tau_over=5.0):
        self.w, self.theta_hi, self.theta_lo, self.tau_over = w, theta_hi, theta_lo, tau_over
    def score(self, E):
        return 1.0 - sum(self.w[k] * E[k] for k in self.w)
    def gate(self, E, request_human):
        A = self.score(E)
        if A >= self.theta_hi: return "AUTONOMOUS"
        if A >= self.theta_lo:
            sig = request_human(deadline=self.tau_over)   # 人在环
            return "AUTHORIZED" if sig else "HOLD"
        return "REFUSE"
```

class AccountabilityChain:
    def __init__(self):
        self.prev = "GENESIS"
    def append(self, decision, human_auth_sig=None):
        rec = {
            "time": time.time(),
            "inputs_hash": sha256(decision["inputs"]),
            "model_ver": decision["model_ver"],

    def responsibilities(self, chain, public_key):

        for rec in chain:
            if rec["human_auth_sig"] and verify(rec["human_auth_sig"], public_key):
                out.append(("Human", rec["hash"]))
            elif rec["oversight_missed"]:
                out.append(("Operator", rec["hash"]))
            else:
                out.append(("System", rec["hash"]))
        return out

### IP-167 PLM（专利布局优化）

```python
def patent_layout(mechanisms, families, values, costs, rho, budget):
    # 贪心最大化次模覆盖收益；生产可用 ILP
    chosen, covered = [], set()
    while True:
        best, best_gain = None, 0.0
        for f in families:
            if f.cost > budget: continue
            gain = sum(values[i] for i in f.covers if i not in covered) * (1 - rho[f.id])
            gain /= max(f.cost, 1e-9)
            if gain > best_gain:
                best, best_gain = f, gain
        if best is None: break
        chosen.append(best); covered |= best.covers; budget -= best.cost
    return Layout(chosen, covered_ratio=len(covered)/len(mechanisms),
                  defensibility=sum(values[i] for i in covered) - sum(f.cost for f in chosen))
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| CRL | O(|min R|) 判定/轨迹 | O(|R|) | 极小元支配全格；r₁⪯r₂ 剪枝不丢正确性 |
| CbC | O(|R|) 编译 | O(|R|) | 可靠性 `g_r ∧ e_r ⇒ φ_r`；冲突必升级人工 |
| EAR | O(1)/决策 | O(1) | 三档门控；θ 单调 |
| DAC | O(1) 追加 / O(n) 审计 | O(n) | 哈希链防篡改；签名可验 |
| PVE | O(电路规模) 证明 | O(ε 预算) | ZK 可靠性 + ε-DP 隐私 |
| PLM | 贪心 O(|F|²·|M|)；ILP 指数 | O(|M|·|F|) | 贪心 (1−1/e) 近似 |

**正确性定理（CEPT）**：假设 A66–A70 成立：**(A66)** CRL 偏序满足单调可靠性 `r₁⪯r₂ ⇒ (φ_{r₁}⇒φ_{r₂})`；**(A67)** CbC 对每个 r 满足 `g_r ∧ e_r ⇒ φ_r` 且不静默丢弃；**(A68)** EAR 对齐分对各风险分量单调不增；**(A69)** DAC 哈希链与签名不可伪造（标准假设）；**(A70)** PVE 的 ZK 系统可靠且知识健全、DP 机制满足 ε-DP。则：
1. **合规可靠性**：若执行轨迹满足编译守卫并产生证据义务，则 `Compliant(C, τ)=1`（构造性合规，无需事后补证）。
2. **不可静默违规**：合规与安全冲突时系统只能升级人工或拒绝，不存在「自动放宽后继续运行」的路径。
3. **可问责性**：任一决策可沿 DAC 追溯到 Human/Operator/System 三类责任主体，且链完整性可在零信任边缘下复算。
4. **隐私-审计守恒**：ZK 证据使审计准确率与 ε 解耦；统计证据受 ε 约束但披露有界。
5. **布局可防御性**：贪心解的可防御性 ≥ (1−1/e)·OPT；若 FTO 距离 < d_min，部署被硬阻断。

### IP-161 CRL（合规需求格）

```python
class ComplianceRequirementLattice:
    def __init__(self):
        self.requirements = {}   # id -> (predicate, refines, standard_ref)
        self.min_elements = set()
    def add(self, rid, predicate, refines=(), std_ref=""):
        self.requirements[rid] = (predicate, set(refines), std_ref)
        self.min_elements.add(rid)
        for r2 in refines:
            self.min_elements.discard(r2)
    def compliant(self, evidence):
        return all(self.requirements[r][0](evidence) for r in self.min_elements)
    def audit_report(self, evidence):
        return {r: bool(self.requirements[r][0](evidence)) for r in self.requirements}
```

### IP-162 CbC（合规构造编译器）

```python
class ComplianceCompiler:
    def __init__(self, ertc, eeis):
        self.ertc, self.eeis = ertc, eeis
    def compile(self, lattice):
        guards, obligations, proofs = [], [], []
        for rid, (phi, _, std) in lattice.requirements.items():
            g_r = self._derive_guard(rid, phi)
            e_r = self._derive_evidence(rid, phi)
            guards.append(g_r); obligations.append(e_r)
            proofs.append(self._circuit(phi))
        C_comp = self.ertc.intersect(guards)
        if self.ertc.meet(C_comp, self.eeis.K_safe) is None:
            return ESCALATE_HUMAN
        return CompiledCompliance(C_comp, obligations, proofs)
```

### IP-163 EAR（伦理对齐门）

```python
class EthicalAlignmentGate:
    def __init__(self, w, theta_hi=0.85, theta_lo=0.55, tau_over=5.0):
        self.w, self.theta_hi, self.theta_lo, self.tau_over = w, theta_hi, theta_lo, tau_over
    def score(self, E):
        return 1.0 - sum(self.w[k] * E[k] for k in self.w)
    def gate(self, E, request_human):
        A = self.score(E)
        if A >= self.theta_hi: return "AUTONOMOUS"
        if A >= self.theta_lo:
            sig = request_human(deadline=self.tau_over)
            return "AUTHORIZED" if sig else "HOLD"
        return "REFUSE"
```

### IP-167 PLM（专利布局优化，次模贪心）

```python
def patent_layout(mechanisms, families, values, costs, rho, budget):
    chosen, covered = [], set()
    while True:
        best, best_gain = None, 0.0
        for f in families:
            if f.cost > budget: continue
            gain = sum(values[i] for i in f.covers if i not in covered) * (1 - rho[f.id])
            gain /= max(f.cost, 1e-9)
            if gain > best_gain:
                best, best_gain = f, gain
        if best is None: break
        chosen.append(best); covered |= best.covers; budget -= best.cost
    return Layout(chosen, covered_ratio=len(covered)/len(mechanisms),
                  defensibility=sum(values[i] for i in covered) - sum(f.cost for f in chosen))
```

**正确性定理（CEPT）**：若 A66–A70 成立（CRL 单调可靠、CbC 可靠性且不静默丢弃、EAR 单调、DAC 不可伪造、PVE 可靠健全），则：
1. 轨迹满足编译守卫并产生证据义务 ⇒ `Compliant(C,τ)=1`。
2. 合规/安全冲突时系统只能升级人工或拒绝，不存在静默放宽路径。
3. 任一决策可沿哈希链追溯到 Human/Operator/System，零信任边缘下可复算。
4. ZK 证据使审计准确率与 ε 解耦；统计证据披露有界。
5. 贪心布局可防御性 ≥ (1−1/e)·OPT；FTO 距离 < d_min 时部署被硬阻断。
