## 1. 两个灵感的第一性原理

### 灵感 1 ·「角色一致性」→ 执行栈是分布式系统：单写者、租约、围栏

**直觉**：一支乐队能演奏，不是因为每个乐手全能，而是因为每个人守住自己的声部；鼓手一旦去拉小提琴，整体就崩。第 2 轮的执行栈已经分工（VLA 管语义、伺服管最后一厘米、断言管确认、介入管恢复），但分工是**隐式**的：动作由 `a=(1−β)a_VLA+βu_servo` 连续混合，等于让两个乐手同时按同一个键——一旦失败，你既不知道是谁的错，也无法阻止两人互相拉扯。

**严谨转译**：把执行栈当成一个**单写者分布式系统**。动作是共享寄存器，角色是进程，权威是写锁。角色一致性 = 任一时刻恰有一个角色持有动作权威，且其写入落在自己的作用域与不变量内。于是有三类与并发系统同构的病：

- **角色碰撞（role collision）**：两个角色同时写（`β∈(0,1)` 即典型共写）→ 抖振、不可归因；
- **角色真空（role vacuum）**：没人写（断言失败后既不让伺服接管、也不让 VLA 继续）→ 停摆；
- **角色漂移（role drift）**：写者正确但越界（伺服改了夹爪语义、VLA 在 align 相位继续开环推进）→ 静默破坏。

**关键机制（本轮真正的技术增量）**：借用分布式系统的**租约 + 围栏令牌（lease + fencing token）**。每次权威转移递增一个 epoch；任何携带旧 epoch 的动作在发出前被丢弃。这恰好解决第 2 轮 IP-03 一直悬着的**陈旧 chunk 竞态**：VLA 在 t 时刻算出的 chunk，可能在伺服于 t+Δ 接管后才到达——旧 epoch 的动作必须被围栏，而不是被「平均」进去。**角色一致性因此不是文档规范，而是一个能在毫秒级执行的运行时协议。**

**另一层（训练角色 vs 部署角色）**：行为克隆估计的是专家在「跟随者」角色下的 `P(a|o)`；测试时却要同一个网络兼任规划者、验证者、恢复者。这是**角色维度的 off-policy**——不是状态分布偏移，而是「职责分布」偏移。因此 critic（断言器）必须与 actor 解耦（外置规则/独立特征/held-out 训练），不能指望 actor 自我确认；这与 IP-02「高精度低召回」的保守介入天然一致。

**再一层（跨本体角色）**：UnifoLM 全语料含 R1、Dex3、G1——若「grasp/align/insert」在跨本体上扮演同一功能角色，则角色等变表征可能提升迁移。此点列为 Q13 探索，不进 MVP（见 §6 修剪纪律）。

### 灵感 2 ·「可用性评估」→ 两条鸿沟，和「全失败区间」里唯一的学习信号

**直觉**：一把好用的工具，不只是「能完成任务」，而是「人知道它何时会失败、失败后能多快修好」。HCI 的可用性从来不是单一成功率，而是**有效性 × 效率 × 满意度**；机器人策略却长期只用有效性衡量。在榜单封闭的情报真空期，**迭代速度就是竞争力**，而可用性正是迭代速度的度量。

**严谨转译**：用 Norman 的**执行鸿沟 / 评估鸿沟**重写可用性：

- **执行鸿沟（Gulf of Execution）**：把一个新任务部署到策略上，需要多少人手工编辑？（手工写路标 = 鸿沟大；零手工 = 鸿沟小）——这是**泛化**的操作化定义。
- **评估鸿沟（Gulf of Evaluation）**：一个 episode 结束后，人多快能说清「发生了什么、为什么」？（`T_diag` 与解释保真度）——这是**可诊断性**的操作化定义。

于是「可用性评估」不是软指标，而是**研究过程本身的元指标**：执行鸿沟大 → 实验慢；评估鸿沟大 → 结论错。再叠加 Nielsen 十启发式作为检查清单（系统状态可见、与现实匹配、用户控制与自由、一致性与标准、错误预防、识别而非回忆、灵活高效、极简、帮助诊断恢复、帮助文档），就得到一套可逐项打分的**执行栈可用性量表**。

**最硬的一条论证（L12，见产物区）**：在最难任务上，成功率常常是 0/0——所有候选都全败，成功率对「谁更好」的信息量为零，模型选择失效；而可用性信号（阶段通过数、到目标距离、干预次数、诊断时间）在这些维度上仍有序。**所以可用性评估不是「锦上添花」，而是难任务区间里唯一有分辨力的学习信号**——恰好是胜负所在。

**必须的守门（否则 Goodhart）**：优化可用性会奖励「少干预但什么都不做」的被动策略。故 OUS 只用于**模型选择与调试**，且必须满足有效性下限（成功率 ≥ 基线 − ε）；绝不用 OUS 替代排行榜目标。

### 两个灵感为何必须成对

角色一致性是**设计性质**，可用性评估是**测量仪器**，二者互为前提：角色不一致 → 失败无法归因 → 评估鸿沟变大；而可用性指标（`T_diag`、干预次数）正是检验角色契约是否生效的经验信号。三者构成闭环：**IP-13 让角色干净 → IP-14 用干净的角色做因果归因 → IP-15 用两条鸿沟度量并元评估 IP-06**。

## 3. 设计原则（新增 P10–P12）

- **P10（单写者优先于数值混合）**：任何模块交互必须是显式契约 + 权威转移 + 回读（readback）；β 只表示「单一 owner 内的委托比例」，不表示共写。没有声明 owner 的混合一律不许上线。
- **P11（可诊断性是第一类指标）**：每次发布必须同时报告 OUS（执行鸿沟 + 评估鸿沟）；成功率上升但可诊断性下降的方案，标记为「技术债发布」。
- **P12（评估器也要被评估）**：IP-06 的诊断在被 IP-12 消费前，必须先过元可用性（可复现、可行动、评分者一致性 κ≥0.6）；否则诊断只作参考。

## 1. 新增方法论：角色一致性与可用性评估

### 1.1 角色一致性 = 单写者 + 租约 + 围栏（与并发系统同构）

第 2 轮的 `a=(1−β)a_VLA+βu_servo` 是**共写**：β∈(0,1) 时两个角色同时拥有动作。共写有三个后果：失败不可归因（混淆）、两模块互相拉扯（抖振）、旧 chunk 在新权威接管后仍被平均进去（陈旧写）。把它映射到并发系统，解法是现成的：

| 并发系统概念 | 执行栈对应 | 违约后果 |
|---|---|---|
| 单写者（single writer） | 任一时刻恰一个角色持有动作权威 | 共写 → 抖振、不可归因 |
| 租约（lease） | 权威带有效期，到期必须让出 | 慢 chunk 长期占权 → 停摆 |
| 围栏令牌（fencing token / epoch） | 每次权威转移递增 epoch；旧 epoch 动作丢弃 | 陈旧 chunk 写入 → 静默错动作 |
| 不变量（invariant） | 角色契约内的硬约束（如伺服不得改夹爪语义） | 越界写 → 角色漂移 |
| 死锁/活锁 | 角色真空（无人持有权威） | 停摆 |

**结论**：角色一致性不是「写一份模块职责文档」，而是一个**可执行的运行时协议**；它同时修掉第 2 轮 IP-03 的陈旧 chunk 竞态（围栏令牌）与 IP-09 的 β 混合不可归因问题（单写者）。

### 1.2 可用性 = 两条鸿沟 + Nielsen 十启发式

| 维度 | 操作化 | 度量 |
|---|---|---|
| 有效性 Effectiveness | 加权成功率（含部分进展） | `Eff` |
| 效率 Efficiency | 单位成功的干预次数；新任务部署的手工编辑数 | `G_exec = N_manual / N_task` |
| 满意度/可诊断 Satisfaction | 从 episode 到可行动结论的时间；解释保真度 | `G_eval = T_diag/T_ref + (1−F_expl)` |

**Nielsen 十启发式 → 执行栈检查项**（逐项 0/1/2 打分）：

| Nielsen 启发式 | 执行栈对应检查项 |
|---|---|
| 系统状态可见性 | 日志是否暴露 owner / epoch / wp_idx / 断言置信度 |
| 系统与现实匹配 | 8 类路标词汇是否贴合任务语义、可被人读懂 |
| 用户控制与自由 | 是否有 abort / 回滚，且回滚无副作用 |
| 一致性与标准 | 每个动作是否恰有一个 owner（IP-13） |
| 错误预防 | 越界动作是否在发出前被契约拒绝 |
| 识别而非回忆 | 失败报告是否含证据（帧、量、相位）而非只给标签 |
| 灵活与高效 | chunk 长度/门控是否自适应，难任务不退化 |
| 美学与极简 | 默认配置是否零手工路标 |
| 帮助识别/诊断/恢复 | IP-06 分解 + IP-14 归因，`T_diag` 是否达标 |
| 帮助与文档 | 是否有可复现 runbook 与一键回放 |

### 1.3 与第 2 轮的关系（不是推翻，是显式化）

- β **不删除**：它从「两个角色的混合权重」降格为「**单一 owner 内的委托比例**」。owner 由仲裁器声明，β 只决定 owner 把多少控制权委托给另一个角色的输出。
- 六因子 **不删除**：IP-14 在其上加一层「角色级 Shapley」，把相关因子变成可做 `do()` 干预的因果因子。
- 成功率 **不删除**：IP-15 把它放进「有效性」一栏，另加效率与可诊断性；且 OUS 受有效性下限约束，防 Goodhart。

## 3. 新增 IP 详述

### IP-13 · RoleLease 单写者权威租约 + 围栏令牌 + 漂移检测（P0，新）

- **动机**：第 2 轮的 β 共写让失败不可归因，且旧 chunk 在新权威接管后仍被混合（IP-03 的陈旧写竞态）。角色一致性要求「一个动作恰有一个 owner」。
- **与现有方案差异**：不是给模块写文档，而是**运行时协议**：`(role, epoch)` 租约、围栏丢弃、契约不变量在线检查。β 从「共写权重」降格为「owner 内委托比例」。
- **技术可行性**：高。状态机 + 断言 + 计数器，单卡小时级；复用 IP-09 的相位与 IP-02 的断言。
- **资源**：零训练；接口无新增字段；仅日志增加 `owner/epoch`（本地）。
- **落地步骤**：①定义 4 个角色（act/servo/assert/recover）的写域、不变量、拒绝条件；②实现仲裁器（优先级 recover > servo > act）与 epoch 递增；③在 `get_action` 出口加围栏过滤；④注入延迟/乱序回放，验证陈旧 chunk 被丢弃（E628）；⑤漂移检测先只告警（E629 达标后允许阻断）。
- **风险**：①过度形式化 → 角色真空停摆（见 §9）；②误报阻断正常执行；③日志开销。

### IP-14 · RoleShapley 角色级因果归因（P1，新）

- **动机**：IP-06 的六因子是**相关**分解；课程（IP-12）要的是「改哪个模块能让任务变好」的**因果**答案。角色契约（IP-13）恰好提供了干净的 `do(role)` 干预。
- **差异**：对每个角色子集做「替换/消融」得到 `v(S)`，算 Shapley 值；用蒙特卡洛采样避免 `2^|R|`。角色重叠时 `do()` 不唯一 → 归因不可辨识（L13）。
- **可行性**：中。需要可回放的代理评测（IP-06）与角色开关（IP-13）；采样 64 次/失败 episode 可控。
- **步骤**：①定义值函数 `v(S)`（成功率或负的到目标距离）；②实现角色开关回放；③蒙特卡洛 Shapley；④置换稳定性与人工一致性（E630）；⑤把归因输出接入 IP-12 的课程权重。
- **风险**：①值函数选择偏差；②消融引入分布外状态，使 `v(S)` 失真 ⇒ 用「同状态分支回放」而非从头重跑；③采样方差 ⇒ 报告置信区间。

### IP-15 · UsabilityBench 双鸿沟 + Nielsen 量表（P1，新）

- **动机**：榜单封闭期，迭代速度 = 竞争力；而「成功率为 0」的难任务区间里，成功率无分辨力（L12）。可用性评估提供唯一有序信号。
- **差异**：不是又一张成功率表，而是**两条鸿沟 + 十启发式 + 元评估**：执行鸿沟（零手工部署）、评估鸿沟（`T_diag`/解释保真度）、评分者一致性 κ。
- **可行性**：高（工程 + 流程）；数据=运行日志与失败回放。
- **步骤**：①定义 OUS 与有效性下限；②实现 `T_diag` 计时与解释保真度评分；③Nielsen 量表逐项操作化与两人评分（E631）；④OUS 与留出任务成功率相关性（E632）；⑤Goodhart 守门（E634）。
- **风险**：①Goodhart（被动策略）⇒ 有效性下限 + 仅作选择/调试；②软指标主观 ⇒ κ 门槛；③评分成本 ⇒ 抽样评分。

## 4. 符号与定义（新增 U16–U19；U1–U15 沿用前两轮）

- **定义 U16（角色契约）**：角色 `r=(S_r, A_r, I_r, R_r)`，其中 `S_r` 为可读作用域、`A_r` 为可写动作通道、`I_r` 为不变量集合、`R_r` 为拒绝条件。一次执行是**角色一致**的，当且仅当 `Σ_r owner_r(t)=1` 且当前 owner 的动作落在 `A_r`、满足 `I_r`。违约分三类：碰撞（Σ>1）、真空（Σ=0）、漂移（owner 正确但越界）。
- **定义 U17（角色漂移度）**：`D_r(t)=d(P_obs(a|r,s_t), P_contract(a|r,s_t))`，可用判别器或契约违约率估计；在线告警当 `D_r>θ_r` 连续 `k` 步。
- **定义 U18（可用性 / OUS）**：`OUS = w_e·Eff + w_f·(1−G_exec) + w_d·(1−G_eval)`，其中 `G_exec=N_manual/N_task`，`G_eval=T_diag/T_ref + (1−F_expl)`；约束 `Eff ≥ Eff_base − ε`。
- **定义 U19（角色 Shapley 归因）**：`φ_r = Σ_{S⊆R\{r}} [|S|!(|R|−|S|−1)!/|R|!]·[v(S∪{r})−v(S)]`，`v(S)` 为仅启用角色子集 S 时的回放值。

## 5. 关键算法骨架（新增片段；主体沿第 2 轮 `UniBotSAGEPolicy`）

```python
# ===== IP-13: 单写者权威租约 + 围栏（替换第 2 轮的 β 共写）=====
class Lease:
    def __init__(self):
        self.owner, self.epoch = None, 0

class RoleLeaseStack:
    # U16：4 个角色，每角色 ≤3 条不变量
    CONTRACTS = {
        "act":     dict(writes={"joint_delta"},        inv={"gripper_semantics_frozen"}),
        "servo":   dict(writes={"ee_velocity"},        inv={"gripper_semantics_frozen"}),
        "assert":  dict(writes=set()),                 # 只读 critic（与 actor 解耦）
        "recover": dict(writes={"retreat", "regrasp"}, inv={"no_forward_progress"}),
    }

    def acquire(self, role):
        if self.lease.owner != role:          # 权威转移 → epoch++
            self.lease.epoch += 1
            self.lease.owner = role
        return self.lease.epoch

    def step(self, s, obs):
        role = self.arbiter(s, obs)           # 优先级 recover > servo > act
        ep   = self.acquire(role)
        a    = self.roles[role].act(s, obs)
        if not self.contract_ok(role, s, a):  # U17：越界/不变量破坏
            self.drift.report(role, s, obs)   # 默认只告警
            return self.yield_and_retry(s, obs)   # 绝不静默混合
        return Action(a, epoch=ep)

    def accept(self, action, current_epoch):
        return action.epoch == current_epoch   # 围栏：陈旧 chunk 直接丢弃
```

```python
# ===== IP-14: 角色级 Shapley（蒙特卡洛，避免 2^|R|）=====
def role_shapley(fail_ep, roles, value_fn, m=64):
    phi = {r: 0.0 for r in roles}
    for _ in range(m):
        perm = random.sample(list(roles), len(roles))
        for i, r in enumerate(perm):
            S = set(perm[:i])
            v1 = value_fn(replay(fail_ep, roles_on=S | {r}))
            v0 = value_fn(replay(fail_ep, roles_on=S))
            phi[r] += (v1 - v0) / m
    return phi      # L13：仅当角色契约互斥时，do(role) 唯一、phi 可辨识
```

```python
# ===== IP-15: OUS（带 Goodhart 守门）=====
def usability(trace, base_eff, eps=0.01):
    eff   = weighted_success(trace)
    g_exec = manual_edits(trace) / max(1, n_tasks(trace))
    t_diag = time_to_diagnose(trace, IP06.report(trace))
    g_eval = t_diag / T_REF + (1 - explanation_fidelity(trace))
    ous = w_e*eff + w_f*(1 - norm(g_exec)) + w_d*(1 - norm(g_eval))
    return ous if eff >= base_eff - eps else float("-inf")   # 被动策略被淘汰
```

## 6. 推导（新增引理 L11–L13；L1–L10 沿用前两轮）

**引理 L11（角色一致性的组合上界与归因混淆）** 设每个角色契约违约概率 `≤δ_r` 且权威互斥，则整栈角色一致概率 `≥1−Σ_r δ_r`（union bound）。若两角色可在同一动作上授权（重叠），则对「移除角色 r」的反事实干预不再改变动作集合，`v(S∪{r})=v(S)`，从而 `φ_r=0`，与 r 的真实贡献无关 ⇒ **角色互斥是归因可辨识的必要条件**。∎

**引理 L12（全失败区间的分辨力）** 设真实成功率 `p ≪ 1/n`（评测预算 n 下期望成功数 <1）。任何仅以成功为信号的比较，其分辨力下界约为 `1/n`：低于该量级的策略在样本中全部并列为 0 成功。而 OUS 为有界连续量，均值 `μ≠0`、方差 `σ²`，区分差异 δ 所需样本 `n_O=O(σ²/δ²)`，与 p 无关。故存在区间使 OUS 可分辨而成功率不可分辨 ⇒ **难任务区间里可用性评估是唯一有分辨力的选择准则**。∎

**引理 L13（角色归因可辨识性）** Shapley 归因 `φ_r` 可辨识，当且仅当对每个角色子集的干预 `do(role=r')` 定义良好（无混淆）且值函数在所有子集上有定义。由 L11，角色互斥使 `do` 唯一；契约完备（无角色真空）使 `v(S)` 对所有 S 有定义。二者缺一，`φ_r` 随消融实现而变 ⇒ **IP-13 是 IP-14 的严格前置**。∎
