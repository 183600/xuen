## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（成本控制 → 比赛是带预算的投资组合，不是功能清单）**
直觉：v1.1 有 9 个创新点、6 个 ★★★★ 以上——这不是计划，是许愿。真实成本远不止 GPU：下载/解码 3.7 TB 视频、标注、工程人周、真机评测排期、推理电费，以及最贵的**迭代延迟**（从改代码到拿到可信信号的时间）。成本控制的第一性原理是：**按「每提升一个排行榜百分点/步骤分点的总拥有成本（CPP）」排序，而不是按想法的新颖度排序**；并且先买保险——一个无效提交的期望得分是 0，所以 `P_valid` 是乘在所有分数前面的系数。

**灵感 2（痛点分析 → 先问「这个痛计分吗、有证据吗、修它便宜吗」）**
直觉：我们一直在修想象中的痛。把痛点分析放到计分层面，会看到三件反直觉的事：(a) 榜单是**成功率优先、步骤分只做并列裁决**，所以只提升步骤分的 I5 里程碑工程，边际价值接近 0（除非并列很常见）；(b) 失败不是均匀的，**「近失」episode（步骤分高但成功=0）才是最便宜的成功转化来源**，应优先修它们；(c) 有些「痛」其实是机会（4 个同任务增量），有些致命痛（端口数不匹配、token、延迟尖峰、跨端口状态泄漏）根本没进 v1.1 的台账。

**统一**：成本控制决定「钱花在哪」，痛点分析决定「什么值得花钱」，而官方字典序计分决定「什么才算分」。三者合成一张**成本-痛点 Pareto 投资组合**：第一层买有效性保险，第二层转化近失，第三层才做能力扩展。

## 2. 严谨定义

**定义 1（成本向量与 TCO）**：干预 i 的成本 `C_i=(C_data,C_compute,C_label,C_eng,C_eval,C_infer)`，用预算影子价格 λ 折算为标量 `TCO_i=λ·C_i`。单位统一为「人日 / GPU 小时 / 真机 run / GB」。

**定义 2（计分对齐）**：榜单分数 `S=(S_succ,S_step)` 按字典序比较。干预的 `ΔS=(ΔS_succ,ΔS_step)`；称其**计分有效**当且仅当 `ΔS_succ>0`，或 `ΔS_succ=0 ∧ ΔS_step>0 ∧ P(tie)>τ`。否则为「非计分改进」，默认不投。

**定义 3（痛点与近失）**：痛点 `p=(失败模式, 受影响 episode 集 E_p, 成功损失 L_p=|E_p|/320, 步骤分损失, 可检测性 d_p, 修复成本 c_p)`。近失集 `N_ε={e: success=0 ∧ step_score≥1−ε}`；近失转化率 `R_ε=|N_ε 中被干预转成功|/|N_ε|`。

**定义 4（每分成本 CPP）**：`CPP_i=TCO_i / max(ΔS_succ_i, ε)`。组合选择是带依赖约束的 0/1 背包：`max Σ ΔS_succ_i x_i s.t. Σ TCO_i x_i ≤ B`，依赖如「I2b 必须先有 I10 的 schema 适配」。

**定义 5（证据等级）**：E0 臆测；E1 官方文档；E2 自测离线数据；E3 自测真机。**只有 E2+ 的痛才配拿真机预算**；E0/E1 的痛只能拿离线/廉价预算去「升级证据」。

**定义 6（有效性保险）**：`E[Score]=P_valid·S`。`P_valid` 由端口数、token、并发隔离、延迟 p99、动作合法性决定。保险的 CPP 最高，因为它把 0 变成「可排名」。

## 4. 研究问题（Q9–Q11；Q1–Q8 保留）

- **Q9（每分成本）**：如何在不花真机预算的前提下估计每个干预的 `ΔS_succ` 与 `TCO`，并给出可信的 CPP 排序？离线代理在什么条件下能预测「成功转化」而非仅步骤分？
- **Q10（近失普查）**：用单任务通道（不计分、免费）做分层失败普查，最少需要多少 run 才能把「最贵的失败轴」定位到可行动精度？近失率与成功转化率的方差如何随 run 数下降？
- **Q11（数据契约）**：异构语料的最小安全接入是什么（键映射、robot 归一、IR/_rec 丢弃、帧率/长度对齐）？如何按「边际成功转化」而非「字节数」选择语料子集？

## 5. 设计原则（新增 PR6–PR8）

- **PR6 每分成本律**：每个创新点必须写出「ΔS 机制、证据等级、TCO、CPP」；写不出 CPP 的不进真机预算。
- **PR7 有效性优先律**：`P_valid` 是乘性系数；有效性保险与 PR4 门禁在一切研究之前完成并常驻。
- **PR8 计分对齐律**：成功率优先；只提升步骤分的工程默认降级，除非有证据表明并列概率高。
- PR1–PR5 保留（PR5 数据杠杆律本轮加强为「按帧边际价值」）。

## 7. 本轮最大风险

**一句话**：成本-痛点审计本身可能变成纸上作业——若痛点证据仍停留在 E0/E1、成本数字又是上一轮的旧估计，我们可能把真正修复主导失败轴的那一个创新（最可能是 I3 接触伺服或 I9 检索）误剪掉；因此第一次真机预算必须花在「分轴失败普查」而不是任何模块 A/B 上，用 E2 证据决定 I3/I9 的生死。

## 2. 计分对齐与 CPP 组合选择

### 2.1 为什么步骤分工程被修剪

榜单是字典序：`S_succ` 优先，`S_step` 只在并列时裁决（F25）。因此对任何干预 i：

```
value_i = P_valid · ΔS_succ_i + ΔP_valid_i · S_base + P(tie) · ΔS_step_i
```

当 `P(tie)` 未知且可能很低时，第三项应设为零预算。I5 的里程碑检测器只作用于第三项，故本轮砍掉；I5 只保留「恢复 → 成功转化」这一项（作用于第一项）。

### 2.2 CPP 组合选择（带依赖的 0/1 背包）

```python
# 价值单位：期望排行榜成功率（百分点）；TCO 单位：归一化预算
ITEMS = {
  "I11_validity": dict(dsucc=0.00, dvalid=0.60, tco=1.0, deps=[]),
  "I10_data":     dict(dsucc=0.02, dvalid=0.05, tco=2.0, deps=[]),
  "I4_intervene": dict(dsucc=0.02, dvalid=0.00, tco=2.0, deps=[]),
  "I8_census":    dict(dsucc=0.00, dvalid=0.00, tco=2.0, deps=[]),   # 信息价值另计
  "I1_aug":       dict(dsucc=0.02, dvalid=0.00, tco=4.0, deps=["I8_census"]),
  "I2b_twin":     dict(dsucc=0.01, dvalid=0.00, tco=5.0, deps=["I10_data", "I8_census"]),
  "I9_retrieval": dict(dsucc=0.01, dvalid=0.00, tco=3.0, deps=["I8_census"]),
  "I5_recovery":  dict(dsucc=0.01, dvalid=0.00, tco=4.0, deps=["I8_census"]),
  "I3_servo":     dict(dsucc=0.01, dvalid=0.00, tco=4.0, deps=["I8_census"]),
}

def portfolio(budget, base_succ, items=ITEMS):
    # 先买有效性（乘性），再按 (P_valid*dsucc + dvalid*base_succ)/tco 排序
    chosen, spent = [], 0.0
    p_valid = 1.0 - sum(0 for _ in chosen)          # 由 I11 预检结果回填
    while True:
        cand = []
        for k, it in items.items():
            if k in chosen or spent + it["tco"] > budget:
                continue
            if any(d not in chosen for d in it["deps"]):
                continue
            val = p_valid * it["dsucc"] + it["dvalid"] * base_succ
            cand.append((val / it["tco"], k))
        if not cand:
            break
        _, k = max(cand)
        chosen.append(k); spent += items[k]["tco"]
    return chosen, spent
```

**依赖的物理含义**：I2b/I9/I1/I3 都必须等 `I8_census` 产出 E2 证据；I2b 还必须等 `I10_data` 的 schema 适配通过，否则混采会静默错位。

```python
CANON = {
    "head_stereo_left":  "observation.images.cam_left_high",
    "head_stereo_right": "observation.images.cam_right_high",
    "wrist_left":        "observation.images.cam_left_wrist",
    "wrist_right":       "observation.images.cam_right_wrist",
}
EVAL_KEYS = set(CANON.values())

def adapt_episode(raw_obs, src_name):
    out = {}
    for k, v in raw_obs.items():
        name = k.split("images.")[-1] if "images." in k else k
        if name in CANON:
            out[CANON[name]] = v
        elif name in EVAL_KEYS:
            out[name] = v
        elif name.endswith("_ir") or "_ir1" in name or "_ir2" in name or name.endswith("_rec"):
            continue                      # 评测没有这些流，默认丢弃
        else:
            continue
    assert EVAL_KEYS <= set(out), (src_name, set(out))
    return out
```

### I8 成本-痛点-消融调度器（升级）★★★★★

- **动机（P7/P13/P14）**：真机预算稀缺，且我们不知道「哪条泛化轴最贵」。先做**分轴失败普查**，再做模块消融。
- **本轮升级**：
  - **普查**：单任务通道（不计分）上做分层抽样（8 任务 × 5 轴 × 1–2 次 ≈ 40–80 run），记录 success、step、终态、近失标记；

  - **CPP 注册表**：每次「离线预测成功转化 vs 真机实测」回填，滚动 Spearman；

- **技术可行性**：高（以离线/单任务通道为主）。
- **所需资源**：1 人周 + 单任务通道排期。
- **落地步骤**：①普查协议与记录 schema；②近失标注；③CPP 注册表；④首个用例 = I10 同任务增量；⑤每周更新排序。
- **风险**：单任务通道与正式评测分布有差（缓解：只在单任务通道做**相对**排序，不用绝对值）；普查 run 数太少（缓解：先算方差，按需加 run）。

```python
def near_miss_census(tasks, axes, runs_per_cell=2):
    rows = []
    for task in tasks:
        for axis in axes:
            for r in range(runs_per_cell):
                ep = run_single_task_channel(task, axis)     # 不计分
                rows.append(dict(task=task, axis=axis,
                                 success=ep.success, step=ep.step_score,
                                 near_miss=(not ep.success and ep.step_score >= 0.7),
                                 terminal=ep.terminal_state))
    # 每条轴的“最便宜成功转化”排序：近失数 / 修复估计成本
    return rank_by_cheapest_conversion(rows)
```

```python
def frame_balanced_weights(challenge_frames, corpus_frames, corpus_share=0.35):
```
