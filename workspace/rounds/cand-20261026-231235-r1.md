# 第 8 轮 · TRIAGE：把 180 秒变成多次可验证尝试（6D 位姿裁判 + 人机残差 + 多机端口）

> 检索/复核日期：**2026-10-26（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「6D位姿估计」「人机交互」「多机评测」。我先用官方手册纠偏三件事——**排名是成功率的字典序、不是步骤分加权；每个任务 10 次 = 5 类泛化 ×2；评测是 N 台机器人、N 个连续端口、随机任务分配**——再合成主判断：**这届比赛最缺的不是再训一个更大的 VLA，而是把 180 秒从“一条开环长轨迹”改写成“多次可验证的恢复尝试”。6D/3D 位姿是把“成功/失败/可恢复”钉在度量空间里的裁判；人机交互不是额外分类器，而是机器人自身动力学解释不了的残差；多机评测不是部署细节，而是 per-port 状态隔离、标定与延迟稳定的硬约束。**

## 0. 本轮先核实：八个会改变资源分配的事实

### 0.1 排名是字典序：成功率 > 步骤分 > 提交时间

官方手册写得很清楚（[S2][S3]）：

```text
实时榜单按 32 个任务的总平均成功率进行排序；
成功率相同时，按总平均步骤分排序；
若仍相同，则提交日期较早的模型排序靠前。
```

并且“最优成绩评定”取多次完整计分评测里**总平均成功率最高的一次**；若相同，再取总平均步骤分最高的一次；若仍相同，取提交时间最早的一次（[S2]）。这意味着：

- **步骤分只在成功率打平时才起作用。** 一个“做完 90% 步骤但最终失败”的 episode 仍然是失败；它不能替代成功。
- **恢复动作不直接扣步骤分。** 手册说步骤分统计“过程中完成的关键步骤”，不是原始动作数；多做几次抓取/对准不会直接扣分。但恢复不能把已经完成的关键步骤**撤销**（例如拉上拉链又拉开、叠好又拿下来），否则步骤分可能回退。
- **多次完整提交是允许的，榜单保留最好的一次。** 这降低了“一次失手”的风险，但每队每天只能预约一个真机时段（[S2]），所以官方跑仍然稀缺，不能当日常迭代。

### 0.2 一次计分跑 = 320 个 episode；每个泛化轴只有 64 个

手册（[S2]）与任务页（[S1]）：每个任务 10 次独立运行，5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰）各 2 次；32 个任务合计 **320 个 episode**。算术：

```text
1 个 episode 对总成功率的权重 = 1/320 = 0.3125pp
1 个任务满分权重           = 10/320 = 3.125pp
1 个泛化轴                 = 64 个 episode = 20%
在 p≈0.3 时：总体 SE≈2.56pp；单轴 SE≈5.73pp；单任务 SE≈14.49pp
检测 +5pp 需要约 1,317 个 episode/组；一次官方跑只有 320 个
```

**结论：官方 320-episode 跑是“终局确认”，不是“日常迭代”。** 日常必须用离线 replay、配对分析、单任务调试槽和小规模真机实验；否则会把 2–3pp 的噪声当方法收益，或者把真正的 5pp 改动误杀。本报告所有“预期收益”都标可检测性，不把 1–2pp 的离线差异当承诺。

### 0.3 WLA-1.0-Base 已经发布：底座不再是瓶颈

宇树在 **2026-09-28** 发布了 `UnifoLM-WLA-1.0-Base` 与微调代码（[S7][S8][S9][S23]）：

- 6B 参数；约 2,500 小时真机数据；64 个任务；桌面 + 全身；支持两指夹爪与多种五指灵巧手；本赛道的 Dex1 在支持范围内。
- 权重 `checkpoints/model.safetensors` 约 **12.46 GB**，Apache-2.0；HF 页面最后更新 2026-09-28。
- 官方微调配方：**冻结 Qwen-VL 主干，只训 DiT 动作专家 + robot-state projector**；默认单卡 **24GB** 显存；支持全参动作专家微调、LoRA、从零训练。
- 这确认了第 7 轮的判断：底座可用、单卡可微调、单模型合规。**任务知识本身大概率不是最大瓶颈**；更大的边际收益在“推理时知道什么时候错了、还能不能救、要不要重试”。

### 0.4 数据有“标定与进度”，没有“物体位姿/子任务/成功标签”

HangCup 的 `meta/info.json` 与 `meta/stats.json`（[S6]）给出：

- 头戴双目已标定：`camera_params.head_stereo`，`rectified=true`；`fx≈282.37/281.87`，`fy≈282.75/282.32`；基线 `T=[-58.25, -0.17, 0.58] mm`，即 **B≈58.25mm**。
- 还有 `state_d435`（头相机在 base 系的 6D 位姿）、`state_torso`、`waist_state_joint`、`lower_body[15]`（12 腿 + 3 腰）、左右 EE 位姿、夹爪开度。
- **没有 depth、没有 mask、没有物体 6D 位姿、没有子任务标签、没有成功/失败标签。** 只有 4 路 RGB、关节/EE/夹爪/躯干/waist、动作、`frame_index`、`episode_index`、`task_index`。
- 全量 32 个数据集：**33,276 条 / 18,282,246 帧 / 169.28 小时**；每条约 969–1,533 条；30fps；单条平均时长 **6.2–37.6 秒**（[S5][S22]）。

这决定了三件事：**(1)** 任何 verifier 必须自监督或伪标签，不能等物体位姿标注；**(2)** `frame_index / episode_length` 是免费的密集进度标签，可以直接训“任务进度”头；**(3)** 成功演示里天然包含失败抓取后的重试片段，可以挖出“自然恢复”样本。

### 0.5 180 秒足够 2–3 次尝试，连最长的任务也够

按 1.5× 演示时长估一次尝试，180 秒的尝试次数：

| 任务 | 平均时长 | 180/时长 | 尝试@1.5× | 尝试@2× |
|---|---:|---:|---:|---:|
| T09 ToolboxStorage（最长） | 37.6s | 4.8 | **3.2** | **2.4** |
| T23 StorePaddle | 34.1s | 5.3 | 3.5 | 2.6 |
| T22 SpellRobot | 31.2s | 5.8 | 3.8 | 2.9 |
| T01 HangCup（最短） | 6.2s | 28.9 | **19.3** | **14.5** |

全部 32 个任务在 1.5× 下都至少有 **3.2 次**尝试预算；在 2× 下也至少有 **2.4 次**（完整表见产物区 §1.4）。**物理上，180 秒从来不是“只够做一遍”；真正的瓶颈是模型不知道当前尝试已经失败、或者失败后还能不能救。**

### 0.6 人机交互是 20% 的分数，不是边角

每个任务 10 次里 **2 次是人为干扰**（5 类 ×2）。如果模型在人为干扰轴上全失败，单任务成功率上限就是 **80%**；如果从 10% 提到 30–50%，总体成功率约 **+4~+8pp**；如果从 10% 提到 90%，是 **+16pp**。这不是小数。官方还给了逐任务的人类干扰剧本（[S2] 的 `generalization` 字段，第 7 轮已整理）：多数是“把某物体平移一次”或“完成某步后撤销”（例如 T27 叠了第二个之后拿下第二个、T19 拉上拉链之后拉开、T14 拧开盖子之后拧动回来、T24 把快到传送带终点的可乐放回起点）。

**关键不是识别“人”，而是识别“机器人自己的动作解释不了的物体位移”。** 人类干扰在机器人动力学里就是一个外生残差；这个残差可以直接触发“暂停—重看—重规划—恢复”，不需要额外的人体检测器。

### 0.7 多机评测是 N 个连续端口 + 随机任务 + 状态隔离

手册（[S2]）与提交模板（[S4]）：

- 评测在 **N 台 G1** 上进行，N 由组委会另行通知（手册示例 N=5）；选手须暴露从 **8765 起的 N 个连续端口**，每个端口对应一台机器人。
- **同一任务的 10 个泛化场景在同一台真机上评测；不同任务在每次测评中随机分布在各台物理机器人上；同一泛化场景在多次测试中也可能换机器人。**
- 每个端口必须独立、稳定地完成整条交互；`reset()` 与历史状态须严格隔离；不同端口可能被同时调用，共享后端必须能并发处理、避免相互阻塞拉高时延。
- 评测器会记录 **per-step response latency、latency variability、action regularity**，并可能随成绩公布（[S4] §6）。

这意味着：**per-port 标定、状态隔离、延迟稳定是官方硬约束，不是“部署细节”。** 一个跨端口状态泄漏或一个端口的标定错误，可能把 1/N 的分数直接打成零；N=5 时就是 20pp。第 6 轮的 FLEET 检查单在本轮升级为 PACS（Port-Aware Calibration & State isolation），进入主线。

### 0.8 榜单仍是占位，不能用来推“头部在做什么”

`leaderboard.html` 仍是「即将发布 / Coming Soon」；`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，8 个模型 ×32 任务 = 256 条 `task_metrics`（[S10][S11]）。结构也暴露了它是生成的：每个模型的逐任务 `step_score / success_rate` 几乎是同一常数（约 1.305–1.371），任务级相关系数精确到 1.000000。**这 8 行只能当 UI 预览，不能当模型强弱、任务难度或失败位置的证据。** 第 7 轮从“步骤分−成功率≈8.6pp”推“失败集中在后段”的用法，本轮降级为弱先验，不作证据。

## 1. 三个灵感词，各自钉到官方事实上

### 1.1 6D 位姿估计：不是“再训一个位姿模型”，是把位姿当裁判

本赛道有头戴双目 + 已标定内外参 + EE 位姿 + 腰部关节，天然可以算度量 3D。但官方 API（[S4]）只给 4 路 RGB、关节/EE/夹爪、`lower_body`，**不给 `state_d435`、`camera_params`、`state_torso`**；所以测试时要用“数据集拟合 + 腰部关节 + 固定安装”把相机位姿算出来，再用双目视差得到物体/容器/支撑面的度量 3D。双目深度误差（0.5px 视差）：

| 距离 | 0.5px 误差 | 1px 误差 | 能做什么 | 不能做什么 |
|---:|---:|---:|---|---|
| 0.3m | 2.7mm | 5.5mm | 腕部近景、粗抓取 | 亚毫米插入 |
| 0.5m | 7.6mm | 15.2mm | 桌面物体中心、容器口 | 精密对孔 |
| 0.8m | 19.5mm | 39.0mm | 场景布局、支撑面 | 小零件位姿 |
| 1.0m | 30.4mm | 60.9mm | 粗略避障 | 任何精密操作 |

所以本轮不把双目当“精密测量”，而把它当 **verifier 的度量骨架**：判断物体是否在目标区、是否还抓得住、是否被人挪走、当前尝试是否还值得继续；最后几厘米的插入/对孔仍用腕部 RGB + EE 伺服。位姿估计不必是 CAD 模板匹配：已知类别可用 category-level（F2G-Pose 28FPS、Flow6D 70FPS，[S19][S20]），未知物体可用“抓取器中心 + 点云主轴 + 抓取相对位姿”，或者只用双目点云的质心/支撑面。OmniRobotHome 的 RGB 双目 + FoundationStereo + FoundationPose 管线跑到约 16Hz（[S18]），证明“双目 + 6D 跟踪”在工程上可行；但我们是单双目 + 6B VLA，必须把位姿降到 5–10Hz、只做 chunk 级裁判，不能每步都跑。

**合规写法：** 推理路径只允许一个学习模型（WLA-1.0-Base + 同 checkpoint 的辅助头）；双目几何、点云配准、PnP 是确定性代码；F2G-Pose/FoundationPose 只做离线教师/伪标签，不进推理；如果必须用学习位姿，就把位姿头蒸馏进同一 checkpoint。这样既满足“单模型”，又保留 6D 位姿的度量能力。

### 1.2 人机交互：不是“人体检测”，是“机器人动力学的外生残差”

把机器人自己的前向模型写成 `s_{t+1} = f(s_t, a_t)`（s 可以是 3D 物体/夹爪状态，也可以是 VLA 的 latent）。人把物体挪走时，观测到的 `Δs_obs` 与 `f(s_t, a_t)` 预测的 `Δs_pred` 会出现一个**方向不对、且持续**的残差：

```text
e_t = Δs_obs − f(s_t, a_t)
若 ||e_t|| > τ_e 连续 k 个 chunk，且 <e_t, Δs_pred> < 0 或 ||e_t⊥|| > τ_perp
→ 判为外生干扰（人/环境），而不是策略失败
```

这个判据的好处是：不需要人体 detector、不需要人配合、不需要标注；人把物体挪走、把拉链拉开、把碗拿下，都会在残差里留下“动作解释不了”的签名。检测到之后不是“继续按原计划”，而是 **暂停 → 重看 → 更新物体位姿 → 从当前状态重规划 → 选择恢复原语**（重抓、重放、重新对准、推回、换手）。官方的人类干扰剧本（[S2]）可以作为先验/训练数据，但运行时只依赖残差。

与最近工作的差异：SocialVLA（[S17]）利用人的表情/语音/动作反应做失败检测；VLA-Corrector（[S13]）用 latent visual monitor 检测视觉漂移并截断 chunk；我们不需要人给信号，也不只是“截断重规划”，而是把外生残差升级为**可恢复性判断 + 时间预算分配**。

### 1.3 多机评测：不是“多卡部署”，是 per-port 的状态、标定与延迟

N 个端口 = N 台机器人 = N 份独立状态。每台机器人的相机安装、桌面高度、光照、初始位姿都可能略有差异；同一任务的不同泛化场景在同一台机器上，但不同任务会换机器。于是：

- **状态隔离**：`reset()` 必须清空 per-port 的 history、SSG/进度状态、动作缓存；任何全局 mutable state 都是 bug。用两个模拟端口交错 reset 的单元测试来审计。
- **per-port 标定**：数据集给出 `state_d435` 与 `waist_state_joint`，可以拟合 `T_base_camera = T_base_torso(waist) · T_torso_camera`；测试时用 `lower_body` 的 3 个腰关节算 `T_base_torso`，再用数据集拟合的 `T_torso_camera`。每个端口第一次 episode 时，可让夹爪在视野内做 1–2 个已知位姿，检测夹爪角点做 PnP，细化 `T_torso_camera`；如果规则不允许 episode 前运动，就直接用数据集先验，标定作为可选增益。
- **延迟与并发**：官方推荐“N 个端口各跑一个进程、各自加载一份模型，互不影响、实现最简单；代价是 N 份显存”（[S2]）。WLA-1.0-Base FP16 约 12.5GB，N=5 份约 62.5GB，5×24GB 或 2×48GB 可以放下；比“共享后端 + 请求分发”更容易保证 p95 延迟。共享后端方案必须做 per-port 队列、并发限流、超时保护。
- **交互质量**：动作要合法、平滑、无 NaN/Inf；延迟要稳定；否则可能被安全终止或降低可信度（[S4] §6）。IQG 是合规件，不是可选项。

## 2. 本轮主判断：把预算从“做一遍”改成“可验证地做多次”

### 2.1 目标函数：先最大化完整成功率，再谈步骤分

第 7 轮把“终局步骤占 39.8%、放置类占 59.7%”当作步骤分大头，方向没错，但目标函数要改写：**排名是成功率的字典序，步骤分只在平局时起作用。** 因此：

- 一个“把 T27 从叠到第二层但没叠第三层”变成“完整叠三层”的改动，价值是成功率 +1 个 episode；一个“某步从 30 分做到 40 分但整任务仍失败”的改动，在排名上几乎不值钱。
- 恢复/重试只要不撤销已完成的关键步骤，就不直接扣步骤分；它可能把失败翻成成功，这是双重收益（成功率 + 步骤分）。
- 反过来，**误判成功而提前停止**、或**误判失败而放弃一个快成功的尝试**，是最大的风险；TRIAGE 的阈值必须保守。

### 2.2 瓶颈不是“会不会做”，而是“知不知道该停/该救”

WLA-1.0-Base 已经在约 2,500 小时、64 个任务上训练过（[S7]），大概率见过这些桌面任务族；占位榜头部成功率 <30% 只是弱先验，但真实比赛的低成功率说明：**即使模型会做，也会在执行中 drift、被干扰、抓空、放歪，然后一路错到底。** 最近的 test-time verification 工作（VLA-Corrector [S13]、DiVeR [S14]、VeriVLA [S15]、CheckVLA [S16]）都证明了“执行中验证”能显著提成功率，但它们主要在**单次尝试内**做 action selection / chunk 截断 / 重规划；**没有人把“这次尝试还值不值得继续、失败后还能不能恢复、剩余时间够不够再试一次”建模成一个时间预算下的恢复决策。** 这正是 TRIAGE 的位置。

### 2.3 重试经济学：p=0.25、ρ=0.5–0.9、r=2–3 时，+9~+28pp

设：

- `p` = 一次完整尝试的成功率；
- `ρ` = 一次失败后场景仍“可恢复”（物体还在桌上、还抓得住、没出工作空间）的概率；
- `r` = 180 秒内最多尝试次数；
- 失败后只有 `ρ` 的概率能进入下一次尝试。

则 r 次尝试的总成功率：

```text
S_r = p · (1 − ((1−p)ρ)^r) / (1 − (1−p)ρ)      (ρ<1)
S_r = 1 − (1−p)^r                              (ρ=1)
```

取 p=0.25（占位榜头部成功率的保守先验），敏感性：

| ρ | r=2 | r=3 | r=4 |
|---:|---:|---:|---:|
| 0.5 | 34.4% (+9.4pp) | 37.9% (+12.9pp) | 39.2% (+14.2pp) |
| 0.7 | 38.1% (+13.1pp) | 45.0% (+20.0pp) | 48.6% (+23.6pp) |
| 0.9 | 41.9% (+16.9pp) | 53.3% (+28.3pp) | 61.0% (+36.0pp) |
| 1.0 | 43.8% (+18.8pp) | 57.8% (+32.8pp) | 68.4% (+43.4pp) |

即使 ρ 只有 0.5，2–3 次尝试也有 **+9~+13pp**；ρ=0.7 时 **+13~+20pp**。这不是“把 base model 换大”能轻易拿到的量级。风险是：p 和 ρ 都是未知的，verifier 误判会吃掉收益；所以第 4 节给了可证伪门槛。

### 2.4 人机交互：20% 的分数，+4~+8pp 的现实区间

如果非人干扰轴基线 25–35%、人干扰轴基线 10%，把人工干扰成功率提到 30–50%：

```text
总体 = 0.8 × 非人 + 0.2 × 人
0.8×0.30 + 0.2×0.10 = 0.26  →  0.8×0.30 + 0.2×0.30 = 0.30  (+4pp)
0.8×0.30 + 0.2×0.10 = 0.26  →  0.8×0.30 + 0.2×0.50 = 0.34  (+8pp)
```

最大理论增益是 +16pp（人干扰从 10% 到 90%），但多数人类干扰可能不可恢复（物体被拿出工作空间）；所以现实目标是 **+4~+8pp**，并且要和 TRIAGE 的重试收益分开归因。

### 2.5 多机评测：可靠性乘数，不是研究噱头

N 端口、随机任务、并发调用意味着：**一个端口的状态泄漏/标定错误/延迟尖峰，可能让那台机器人的所有任务归零。** N=5 时，一个端口归零最多损失 20pp。PACS 的目标不是“多拿几分”，而是“不把已有的分丢掉”：

- 零跨端口状态泄漏（单元测试 + 运行日志）；
- 每个端口 p95 延迟 < 500ms（目标，待真机校准）；
- 100% 动作合法、无 NaN/Inf、无超限；
- 标定失败时自动回退到数据集先验，不阻塞 episode。

### 2.6 与第 7 轮的关系：保留骨架，换目标函数

| 第 7 轮 | 第 8 轮决定 | 理由 |
|---|---|---|
| I9 GPR-VLA + WLA 底座 | **保留/升级** | 唯一学习模型；加 PRM/位姿辅助头，仍是单 checkpoint |
| I5 SVL 落点 settle-verify | **升级为 PRM + TRIAGE** | 从“放置后验证”扩展到“全程进度/可恢复性裁判 + 时间预算” |
| I6 NRB 官方备注恢复 | **升级为 HARD** | 从训练期恢复库，升级为运行时外生残差检测 |
| I1 SSG 评分步骤图 | **保留/降级** | 成功是主指标；SSG 作为进度先验与“不要撤销已完成步骤”的守卫 |
| I2 PGL 放置锚点 | **保留/可选** | 放置仍重要，但不是本轮主线；作为 GEST 的目标区先验 |
| I3 OPT 少样本放置位姿 | **保留/收窄** | K=1–4，只在放置阶段；不作为核心押注 |
| I4 ICR 检索条件化 | **降级/砍** | 重资产、延迟高；与成功率字典序不直接对齐 |

## 3. 方案轮廓：TRIAGE（细节在产物区）

```text
观测（4×RGB + 关节/EE/夹爪/waist/language）
        │
        ├── WLA-1.0-Base（冻结 VLM + DiT 动作专家）──> action chunk
        │
        ├── GEST：双目 + EE/waist + 数据集标定 ──> 度量 3D/6D 状态 s_t
        │
        ├── PRM：进度 τ_t / 剩余时间 / 可恢复性 c_t ──> 裁判
        │
        └── HARD：e_t = Δs_obs − f(s_t,a_t) ──> 人/环境外生残差
                    │
              TRIAGE-C：EXECUTE / VERIFY / RECOVER / RETRY / STOP
                    │
              PACS：per-port 状态/标定/延迟；IQG：动作合法性/平滑/看门狗
```

- **PRM（Progress & Recoverability Monitor）**：用 `frame_index/episode_length` 做免费进度标签，训一个小的进度/剩余时间/可恢复性头；在 VLA 特征 + 本体感知上做时序 ranking + 回归 + 单调性约束。运行时看 `Δτ` 是否停滞/回退，结合前向残差 `e_t` 判断“在轨/偏离/卡住/已成功/不可恢复”。
- **GEST（Grounded Episode State Tracker）**：双目 SGBM/FoundationStereo + 点云 + 抓取器中心/容器口/支撑面；用数据集拟合 waist→camera 的运动学；per-port 可选 PnP 细化；输出带置信度的度量状态。位姿只做裁判，不做毫米级插入。
- **HARD（Human-as-Residual Detector）**：用 `Δs_obs − f(s_t,a_t)` 的方向/持续性判外生干扰；官方剧本做先验；触发后暂停、重看、更新状态、重规划。
- **TRIAGE-C**：有限时域状态机 + 阈值；`continue` 当且仅当当前尝试的估计成功率不低于一次新尝试（扣除已完成步骤的保留价值）；否则 `recover` 或 `retry`；最后留 10–15% 预算做收尾/安全停止。
- **PACS / IQG**：N 端口独立上下文、`reset()` 清空、per-port 标定缓存、并发限流、p95 延迟看门狗；动作 clamp/平滑/NaN 检查/超时安全保持。

**单模型合规**：推理路径只有一个学习模型（WLA-1.0-Base + 同 checkpoint 的 PRM/位姿辅助头）；GEST 的双目几何是确定性代码；HARD 的前向模型是同一 checkpoint 的辅助头；TRIAGE-C 是确定性决策，不是第二个策略。F2G-Pose/FoundationPose 只在离线做教师/伪标签，不进推理。

## 4. 可证伪假设与预期收益

| 假设 | 门槛 | 不成立时 |
|---|---|---|
| H1 PRM 能在 held-out 任务上检测“停滞/偏离” | AUROC ≥0.80 | <0.70 → verifier 假设失败，回退单次尝试 + SVL |
| H2 失败后场景可恢复 | 至少 16/32 任务 ρ≥0.5 | ρ<0.3 → 重试收益 <5pp，TRIAGE 降级为“仅恢复不重试” |
| H3 TRIAGE 在完整计分跑上超过 base | +5pp 成功率 | <+3pp → 回退到 base + SVL + IQG，保留 PACS |
| H4 人机干扰轴提升 | 人干扰成功率 +10pp | <+5pp → HARD 只做“暂停重看”，不做重试 |
| H5 多机部署不丢分 | 零跨端口泄漏；p95<500ms | 任一失败 → 先修 PACS，再谈研究收益 |

**预期收益（先验，不是承诺）：** 重试 +9~+20pp（保守 ρ=0.5–0.7，r=2–3）；人机干扰 +4~+8pp；合计 **+13~+28pp** 的成功率空间。但官方 320-episode 跑的 95% CI 约 ±5pp，单次跑无法证明 <5pp 的差异；必须用离线配对 + 多次提交 + 单任务调试槽三角验证。

## 5. 风险与合规（先立后破）

| 风险 | 概率 | 影响 | 缓解 | 停止条件 |
|---|---|---|---|---|
| 单模型规则被判定为“多模型” | 中 | 高 | 推理只用一个 checkpoint；位姿用确定性几何；学习位姿只做离线教师 | 官方明确禁止辅助头 → 把 PRM/位姿蒸馏进动作专家，或只保留 PRM |
| 没有物体位姿/成功标签 | 高 | 中 | 进度用 frame_index 自监督；可恢复性用自然重试 + 合成负例；位姿用 category-level/点云 | PRM AUROC<0.7 → 回退 action-consistency + 夹爪状态 |
| 双目深度不够精密 | 高 | 中 | 位姿只做裁判；最后几厘米用腕部 RGB 伺服 | 位姿误差 >2cm → 该任务退出 GEST |
| verifier 误判导致误 abort | 中 | 高 | 保守阈值 + 持续性检验 + 保留已完成步骤；只在剩余时间足够时 abort | 误 abort 率 >10% → 提高阈值/改为只恢复不重试 |
| 人机干扰不可恢复 | 中 | 中 | 可恢复性头 + 官方剧本先验；优先“重看/重规划”而非盲重试 | ρ<0.3 → 只做暂停重看 |
| 延迟/并发 | 中 | 高 | 一端口一 GPU；FP16/TensorRT；位姿 5–10Hz；异步/缓存；p95 看门狗 | p95>1s → 降级到 PRM-only |
| 外部数据/规则 | 中 | 中 | 默认只用官方数据 + 公开预训练权重；合规模块开关；赛后开源 | 官方禁止 → 关闭外部数据 |
| 榜单占位/规则变化 | 高 | 低 | 只当弱先验；所有阈值可配置；关注手册更新 | 规则变更 → 重新校准 |

## 6. 一句话押注

**如果只能押一件事：把 180 秒从“一次开环长轨迹”改写成“多次可验证的恢复尝试”——用自监督的进度/可恢复性裁判（PRM）判断当前尝试还值不值得继续，用 6D/3D 位姿把裁判钉在度量空间里，用时间预算决策决定继续/恢复/重试；这是唯一同时对齐“成功率字典序第一”、20% 人机干扰和 N 端口多机评测的杠杆。**

## 2. 评分算术与重试经济学

### 2.1 排名与步骤分

```text
最终排名 = 总平均成功率 > 总平均步骤分 > 提交时间
单任务成功率 = 成功次数 / 10（保留两位小数）
总平均成功率 = 32 个任务成功率的平均
步骤分 = 每次执行中完成的关键步骤（即使最终失败也计）
```

策略含义：

1. **先最大化完整成功率。** 一个 90% 步骤但失败的 episode 仍是失败。
2. **恢复动作不直接扣步骤分。** 但恢复不能撤销已完成的关键步骤；SSG 要标记“已完成/不可逆”，恢复原语要避免回退。
3. **误 abort 比多花时间更贵。** 如果当前尝试快成功，abort 会丢掉一个成功；只有当“新尝试的期望成功”显著高于“继续”时才 abort。
4. **多次完整提交保留最好一次。** 但每日一槽，官方跑仍稀缺；不要把噪声当收益。

### 2.2 320-episode 统计功效

| 量 | 值 | 含义 |
|---|---:|---|
| 1 episode 权重 | 0.3125pp | 320 个 episode 的平均 |
| 1 任务权重 | 3.125pp | 10 个 episode |
| 1 泛化轴 | 64 episodes = 20% | 5 类 ×2 ×32 |
| 总体 SE（p=0.3） | 2.56pp | 一次官方跑 95% CI 约 ±5pp |
| 单轴 SE | 5.73pp | 轴级结论很 noisy |
| 单任务 SE | 14.49pp | 不要用单任务 10 次下结论 |
| 检测 +5pp 所需/组 | ≈1,317 episodes | 一次官方跑远不够 |
| 检测 +10pp 所需/组 | ≈329 episodes | 约等于一次官方跑 |

**结论：** 官方 320-episode 跑是“终局确认”；日常迭代用离线 replay + 配对种子 + 单任务调试槽。任何“+2pp”的离线差异都不应当作承诺。

### 2.3 时间预算

见 §1.4。三个直接结论：

- 所有任务在 1.5× 下 ≥3.2 次尝试；2× 下 ≥2.4 次。
- 长任务（T09/T23/T22/T29）仍有 3–4 次；短任务有 10–19 次。
- 真正的约束不是 180s，而是 **一次尝试的失败检测延迟** 和 **失败后场景是否可恢复**。

### 2.4 重试模型

设 `p`=单次尝试成功率，`ρ`=失败后可恢复概率，`r`=最多尝试次数。则：

```text
S_r = p · (1 − ((1−p)ρ)^r) / (1 − (1−p)ρ)      (ρ<1)
S_r = 1 − (1−p)^r                              (ρ=1)
```

| p | ρ | r=2 | r=3 | r=4 |
|---:|---:|---:|---:|---:|
| 0.20 | 0.5 | 28.0% | 31.2% | 32.5% |
| 0.20 | 0.7 | 31.2% | 37.5% | 41.0% |
| 0.20 | 0.9 | 34.4% | 44.8% | 52.2% |
| 0.20 | 1.0 | 36.0% | 48.8% | 59.0% |
| 0.25 | 0.5 | 34.4% | 37.9% | 39.2% |
| 0.25 | 0.7 | 38.1% | 45.0% | 48.6% |
| 0.25 | 0.9 | 41.9% | 53.3% | 61.0% |
| 0.25 | 1.0 | 43.8% | 57.8% | 68.4% |
| 0.30 | 0.5 | 40.5% | 44.2% | 45.5% |
| 0.30 | 0.7 | 44.7% | 51.9% | 55.4% |
| 0.30 | 0.9 | 48.9% | 60.8% | 68.3% |
| 0.30 | 1.0 | 51.0% | 65.7% | 76.0% |

**读法：** p=0.25、ρ=0.5、r=3 → 37.9%（+12.9pp）；ρ=0.7、r=3 → 45.0%（+20.0pp）。即使 ρ 只有 0.5，2–3 次也有 +9~+13pp。**这是本轮最大的、无需换底座的杠杆。**

**模型假设/失效条件：**

- p 与 ρ 未知；用占位榜 p≈0.2–0.3 做先验，用调试槽校准。
- 失败后场景可能不可恢复（物体掉地、出工作空间、透明件卡住）；ρ 由可恢复性头估计。
- 每次尝试有固定开销（回撤、重看、重规划）；用 1.5× 演示时长估 d，并留 10–15% 收尾预算。
- verifier 误判会 abort 一个快成功的尝试；阈值必须保守（§2.5）。
- 恢复动作可能撤销已完成步骤；用 SSG 的“不可逆步骤”标记避免。

### 2.5 继续/放弃阈值

把剩余时间 `t` 的最优成功率记为 `V(t)`，当前尝试估计成功率 `q`，新尝试 `p`，单次尝试时长 `d`，已完成步骤的保留价值 `c_progress`（若重试会撤销，则 >0）：

```text
继续：q + (1−q)ρ·V(t−d) − c_progress
重试：p + (1−p)ρ·V(t−d)
继续当且仅当：q − p ≥ c_progress
```

实用规则：

- 若当前尝试已完成不可逆的关键步骤（物体已入袋、拉链已拉上），`c_progress` 很大 → 优先继续/局部修复，不重试。
- 若当前尝试明显偏离（PRM 停滞/回退、HARD 外生残差、GEST 物体不在目标区），且 `q` 明显低于 `p`，且 `t ≥ d + margin` → 重试。
- 若不确定，**继续**；误 abort 的代价高于多花几秒。
- `margin` 取 10–15% 的 180s（18–27s），用于最后收尾/安全停止。
- `q` 由 PRM 估计：`q = σ(α·τ + β·c + γ·Δτ + δ)`；`p` 用任务先验/演示统计；`ρ` 用可恢复性头。阈值在调试槽校准。

|---:|---:|---:|---:|---:|

### 2.7 多机算术

- N 台机器人、N 个连续端口；任务随机分配。若一个端口因状态泄漏/标定错误/延迟尖峰整体归零，均匀分配下损失约 `1/N`；N=5 → 20pp。
- PACS 的目标是“不丢分”：零跨端口状态泄漏、per-port 标定回退、p95 延迟稳定、动作合法。
- 共享后端省显存，但并发会拉高延迟；官方推荐“N 进程各加载一份”最稳（[S2]）。N=5、FP16 12.5GB/份 → 5×24GB 或 2×48GB 可放下。

## 3. TRIAGE 架构

### 3.1 总览与延迟预算

```text
obs (4×RGB + arm/EE/gripper/lower_body/language)
   │
   ├─ WLA-1.0-Base (frozen VLM + DiT action expert) ──> action chunk
   │
   ├─ GEST: stereo + waist/EE + calibration ──> metric 3D/6D state s_t
   │
   ├─ PRM: progress τ_t / remaining r_t / recoverability c_t ──> verdict
   │
   └─ HARD: e_t = Δs_obs − f(s_t, a_t) ──> exogenous residual
              │
        TRIAGE-C: EXECUTE / VERIFY / RECOVER / RETRY / STOP
              │
        PACS: per-port state/calibration/latency; IQG: action/latency guard
```

| 阶段 | 目标延迟 | 频率 | 备注 |
|---|---:|---|---|
| VLA forward | 100–300ms | 每 chunk | 6B，FP16/TensorRT；实测为准 |
| 双目深度 | 5–20ms | 每 chunk 或 2–3 chunk | SGBM/小模型；640×480 |
| 点云/位姿 | 15–40ms | 5–10Hz | 不必每步；chunk 级裁判 |
| PRM 头 | <5ms | 每 chunk | 小 MLP |
| HARD 残差 | <1ms | 每 chunk | 复用 PRM 前向 |
| TRIAGE-C | <1ms | 每 chunk | 状态机 |
| 合计 p95 | **<500ms** | 每 chunk | 超过则降级 PRM-only |

### 3.2 WLA-1.0-Base 接口

- 唯一学习模型：6B；冻结 Qwen-VL 主干；DiT 动作专家可全参/LoRA；默认 24GB。
- 观测：4 路 RGB、双臂关节、EE 位姿（base）、夹爪、`lower_body[15]`、`language`；动作 chunk 自定。
- **动作 chunk 建议 8–16**（30Hz 下 0.27–0.53s）：足够反应性，又不会每步都付 VLA 前向；在本地 mock 与调试槽测 p95 后定。
- 辅助头（PRM/位姿）挂在 VLM 特征 + 本体感知上，与动作专家同一 checkpoint；训练时可冻结动作专家只训头，或联合微调。
- 不使用第二个策略模型；不按任务切模型/LoRA。

### 3.3 GEST：双目 3D/6D 裁判

**相机到 base：**

- 数据集有 `state_d435` 与 `waist_state_joint`；拟合 `T_base_camera = T_base_torso(waist) · T_torso_camera`。`T_base_torso` 用 G1 URDF/腰部关节正运动学；`T_torso_camera` 用数据集最小二乘/非线性优化。
- 测试时只读 `lower_body` 的 3 个腰关节，算 `T_base_torso`，再乘 `T_torso_camera`。这与直接读 `state_d435` 的误差应在毫米/毫弧度级；用数据集验证。
- per-port 细化（可选）：第一次 episode 让夹爪在视野内做 1–2 个已知位姿，检测夹爪角点做 PnP；若重投影误差下降则更新 `T_torso_camera`，否则保留先验。规则不允许 episode 前运动则跳过。

**物体/目标状态：**

- 头双目：SGBM 或 Fast-FoundationStereo → 点云；用抓取器中心/腕部 ROI 选物体点云；ICP/质心/主轴跟踪。
- 目标区：支撑面/容器口/置物架平面；用深度/平面拟合 + 语言/SSG 先验。
- 已知类别：可选 category-level 6D（F2G-Pose/Flow6D）离线教师/伪标签；未知物体：抓取器中心 + 点云主轴 + 抓取相对位姿，不依赖 CAD。
- 腕部 RGB：最后几厘米的插入/对孔用视觉伺服；头双目不做精密测量。

**双目深度误差（0.5px/1px 视差）：**

| 距离 | 0.5px | 1px | 用途 |
|---:|---:|---:|---|
| 0.3m | 2.7mm | 5.5mm | 腕部近景/粗抓取 |
| 0.5m | 7.6mm | 15.2mm | 物体中心/容器口 |
| 0.8m | 19.5mm | 39.0mm | 场景布局/支撑面 |
| 1.0m | 30.4mm | 60.9mm | 粗略避障 |

**裁判谓词：**

- 成功：物体在目标区、姿态满足任务、稳定（连续 k 帧位姿变化 < ε）、夹爪释放。
- 可恢复：物体仍在桌面/工作空间、未被遮挡、可抓取；剩余时间 > 恢复估计时长。
- 外生干扰：`||Δs_obs − f(s,a)||` 超阈值且方向不对（§3.5）。
- 置信度：视差置信、ICP fitness、重投影误差；低置信 → 只信 PRM/夹爪，不用位姿做 abort。

### 3.4 PRM：自监督进度/可恢复性监视器

**输入：** 冻结 VLM 的 pooled 特征 + EE 位姿/夹爪/waist + 双目点云摘要（可选）。
**输出：** `τ∈[0,1]` 进度；`r≥0` 剩余时间（秒）；`c∈[0,1]` 可恢复性。

**标签（全部自监督）：**

- `τ_t = frame_index/(L−1)`；`r_t=(L−frame_index)/fps`。
- `c_t`：从“自然重试”片段（正）与合成负例（负）构造；或用 `r_t` 与剩余预算比较做弱标签。
- 自然重试挖掘：检测夹爪闭合事件；若闭合后物体未随夹爪移动（腕部 RGB/EE 相对位姿），标为失败抓取；随后夹爪张开并重新接近的片段标为恢复。成功演示里预计有可挖片段（产率 W1 实测）。

**损失：**

```text
L = L_rank(τ_t, τ_{t+k}) + λ1·MSE(τ, τ*) + λ2·MSE(r, r*)
    + λ3·BCE(c, c*) + λ4·ReLU(τ_t − τ_{t+1})
```

- `L_rank`：同 episode 后帧进度应大于前帧（margin ranking），比纯回归更抗速度变化。
- 单调性惩罚：进度不应回退（人把物体挪走/撤销关键步骤时允许回退，但要被 `c`/HARD 捕获）。
- 不用失败标签；合成负例用时间反转、物体位移、动作噪声、跨 episode 打乱。

**运行时：**

- `Δτ_t = τ_t − τ_{t−k}`；连续 m 个 chunk `Δτ < ε` → 停滞；`Δτ < −ε` → 回退。
- 结合前向残差 `e_t` 和 GEST 状态：`verdict = on_track / off_track / success / unrecoverable`。
- 阈值用 held-out 成功演示的 95 分位校准；失败阈值用调试槽/合成负例校准。
- 若 PRM 不可信：回退到 action-chunk 一致性（dropout/TTA 方差）+ 夹爪开度 + EE 轨迹似然。

### 3.5 HARD：人机交互作为外生残差

```text
e_t = Δs_obs − f(s_t, a_t)
外生判据：||e_t|| > τ_e 连续 k 个 chunk
          且 <e_t, Δs_pred> < 0 或 ||e_t⊥|| > τ_perp
```

- `s` 用 GEST 的度量状态（物体/夹爪/目标）；`f` 用同一 checkpoint 的前向头，或简单的 EE/物体速度预测。
- 方向判据区分“策略自己推偏了”（残差与动作同向/渐进）和“人把物体挪走”（残差与动作反向/正交且持续）。
- 官方人类剧本作为先验：T27 叠了第二个后拿下第二个、T19 拉上拉链后拉开、T14 拧开盖子后拧回、T24 把可乐放回传送带起点（[S2][S24]）。这些都会产生“动作解释不了的位移/撤销”。
- 触发后：暂停 → 重看（新双目/腕部）→ 更新物体位姿 → 从当前状态重规划 → 选恢复原语（重抓/重放/重新对准/推回/换手）。不盲目重试。
- 与 SocialVLA（人的反应信号）[S17]、VLA-Corrector（latent visual drift）[S13] 的差异：不依赖人给信号；不只截断 chunk；把残差升级为可恢复性/时间预算决策。

### 3.6 TRIAGE-C：时间预算恢复控制器

**状态机：**

```text
RESET → CALIBRATE? → EXECUTE
EXECUTE: 每 chunk 边界更新 s, τ, r, c, e
  if success(τ, s): STOP
  if off_track(e, Δτ, s):
      if c > C_MIN and t_remaining > D_RECOVER + MARGIN: RECOVER
      elif t_remaining > D_ATTEMPT + MARGIN: RETRY
      else: CONTINUE (保守) 或 STOP
  else: CONTINUE
RECOVER: 恢复原语 → VERIFY → EXECUTE/RETRY
RETRY: 回撤到安全位姿 → 重看 → 重规划 → EXECUTE
STOP: 安全保持 → 结束
```

**伪代码：**

```python
def act(obs, ctx):
    s = gest.update(obs)
    tau, rem, c = prm.update(obs, s)
    e = hard.residual(s, ctx.last_action)
    v = classify(tau, rem, c, e, ctx)

    if v == SUCCESS:
        return iqg.safe_hold()
    if v == OFF_TRACK:
        t = 180.0 - ctx.elapsed
        if c > C_MIN and t > D_RECOVER + MARGIN:
            return iqg.clamp(recover(v, s))
        if t > D_ATTEMPT + MARGIN:
            return iqg.clamp(retry(s))
    return iqg.clamp(policy.action_chunk(obs))
```

**参数：**

- `D_ATTEMPT = 1.5 × demo_duration`（§1.4）；`D_RECOVER = 0.3–0.5 × D_ATTEMPT`；`MARGIN = 18–27s`（10–15% × 180s）。
- `C_MIN` 由调试槽校准；初始 0.5。
- `q`/`p`/`ρ` 用 §2.5；不确定时继续。
- SSG 的“不可逆步骤”集合：已完成则 `c_progress` 大，禁止会撤销的 retry；只允许局部修复。
- 成功检测：`τ` 接近 1 且 GEST 谓词满足；不确定时继续到超时，不提前停（避免误判成功）。

### 3.7 PACS：per-port 标定/状态隔离

| 方案 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| N 个独立 server（8765..） | 稳定、简单、无跨端口状态 | N 份显存 | **计分跑首选** |
| 共享后端 + N 轻端点 | 省显存 | 并发/延迟/状态泄漏风险 | 调试/备用 |

- `PortContext`：`port_id`、`episode_id`、history、SSG 状态、PRM 状态、标定、延迟统计。
- `reset()` 清空 per-episode 状态；标定缓存可保留但每次 episode 重新校验。
- 单元测试：两个模拟端口交错 reset/任务切换，断言无状态串用；日志带 port/episode/request id。
- 一端口一 GPU（N=5：5×24GB）；FP16/12.5GB/份；warm-up；并发限流；p95 看门狗。
- 标定失败自动回退数据集先验，不阻塞 episode。

### 3.8 IQG：交互质量守卫

- 动作形状/dtype/NaN/Inf 检查；关节限位/速度/加速度限制；EE 步长限制。
- 平滑：低通/限幅；避免抖动/异常大动作。
- 延迟：p50/p95 记录；超时返回安全保持（最后有效动作或零速度），不返回过期 chunk。
- 记录 action norm/jerk/latency；对齐官方可信度指标（[S4] §6）。

- 数据增强：背景替换、干扰物插入、物体替换、颜色/裁剪抖动；默认只用官方数据；外部数据开关默认 OFF。
- 人机干扰：官方剧本用于 HARD 先验/评估；合成扰动只训 PRM/HARD，不直接训策略（避免负迁移）。
- 单模型：辅助头与动作专家同一 checkpoint；不按任务合并 LoRA。

### 4.2 PRM 数据与自然恢复挖掘

- 33k 成功 episodes；按任务/背景/物体分 split；held-out 任务做泛化测试。
- 进度标签免费；排序损失 + 回归 + 单调性。
- 自然重试：夹爪闭合 + 物体未随动 → 失败抓取；随后重新接近 → 恢复片段。产率 W1 统计；若 <1k 片段，补合成负例/调试槽。
- 合成负例：时间反转、物体位移、动作噪声、跨 episode 打乱；用于 off-track/可恢复性。
- 校准：held-out 成功演示 95 分位；失败阈值用合成负例 + 调试槽。

### 4.3 GEST 数据/标定

- 用 `camera_params` 做双目校正；用 `state_d435`/`waist_state_joint` 拟合 waist→camera。
- 物体位姿无标签：离线用 F2G-Pose/FoundationPose 伪标签（只对已知类别/有模板物体）；未知物体用点云/抓取器中心。
- 评估：合成的已知位移、调试槽的受控物体移动；不要用占位榜单。
- 置信度低 → 不用位姿做 abort；只用 PRM/夹爪。

### 4.4 HARD 数据

- 官方人类剧本（[S2][S24]）做先验；调试槽回放/观察真实干扰。
- 合成物体位移/撤销用于阈值校准；不训练人体 detector。
- 恢复原语库：重抓、重放、重新对准、推回、换手、暂停重看；用自然重试片段评估。

### 4.5 算力/延迟

- 训练 8×H100；离线 1×A100；推理 N=5 → 5×24GB（或 2×48GB）。
- FP16/TensorRT；warm-up；位姿 5–10Hz；p95 目标 <500ms；超时降级 PRM-only。
- 成本：计分跑窗口租 5×24GB；调试槽用 1 份模型即可。

## 11. 开放问题

1. **N 的具体值**：手册只给示例 N=5；实际排期时确认。N 决定显存/端口/并发预算。
2. **调试槽是否也跑 10 次**：手册说“只测 1 个任务”，未明确次数；按 10 次做预算，现场确认。
3. **步骤分精确公式**：关键步骤是二值还是部分分？是否允许重复完成/撤销？需要任务 info 的 `score_steps` + 现场详情页确认。
4. **人类备注编号**：`human_1/human_4` 是轴编号还是试次编号？官方未解释；HARD 不依赖顺序，只用剧本做先验。
5. **单模型边界**：辅助头/确定性几何/离线教师是否算“多模型”？当前写法是“推理一个 checkpoint + 确定性代码”；若官方更严格，蒸馏进动作专家。
6. **外部数据**：手册未明确禁止，但有诚信条款；默认只用官方数据 + 公开预训练权重，外部数据开关 OFF。
7. **动作 chunk 动态截断**：API 的 `action_chunk_size` 在 handshake 固定；能否返回“短 chunk”或“安全保持填充”需在 mock/真机确认。当前按固定 chunk + 内部控制实现。
8. **成功信号**：策略不接收评测器的成功/失败信号；只能用 PRM/GEST 自估。若评测器成功即停，策略的“成功估计”只需避免提前停；若不停，需自己停。
9. **官方 model server 的 Dex1 支持**：FCMO 报道称当前 server 文档覆盖 Dex1、不含 WBT；以官方 repo 最新文档为准。
10. **GPU/网络**：计分跑窗口的 GPU 租用、公网端口、并发连接数；提前压测。
