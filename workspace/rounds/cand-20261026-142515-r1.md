# 第 8 轮 · TRIAGE：场景泛化不是换一张背景，而是让失败可诊断、可恢复、可预算

> 检索/复核日期：2026-10-26（UTC）。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），Unitree G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「场景泛化」「失败恢复」「决策规划」。**本区引用编号与产物区 §11 的来源表一致；外部信息的链接与检索日期均在该表。**我先用官方参赛手册纠一个会改变策略排序的事实，再把三个词分别钉到官方结构和 2026 年新证据上，最后给出主判断：**第 7 轮“把最后一步放好”仍然对，但只覆盖了终局；下一块更大的边际收益在“执行层”——让失败在 180 秒内被诊断、路由、恢复，并且知道什么时候值得救、什么时候不值得救。**

## 0. 本轮先纠一个关键事实：排名是“成功率优先，步骤分只做同分裁决”

### 0.1 官方手册把评测结构写死了

我本轮抓到了挑战赛页面挂出的官方参赛手册（中文/英文 Feishu 文档，[S1][S2]），关键条款如下：

- **每任务 10 次独立运行**；10 次里覆盖 5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰），**每类恰好 2 次**（[S1] §2.1）。
- 因此总评测量是 **32 × 10 = 320 次真机 episode**，不是“32 个任务各跑一次”，也不是“成功率与步骤分加权求和”。
- **实时榜单先按 32 个任务的总平均成功率排序；成功率相同才看总平均步骤分；仍相同则提交更早的模型靠前**（[S1] §1.2）。这是一条字典序，不是加权和。
- 每个任务单次真机执行 **最长 180 秒**，超时记为失败，并按执行情况计算步骤分（[S1] §2.1）。
- 只设通才模型赛道；**所有任务必须基于同一模型完成，不得混合多个模型一起测试**；模型类型不限（World Model、VLA 都可以）。另有不计分的单任务调试通道（[S1] §1.1–1.2；[S3]）。
- 官方数据资源是 32 个任务的全部真机采集数据（[S1] §2.2）。

这条修正很重要：第 7 轮把“平均成功率与步骤分综合排序”理解成近似加权，进而用“终局步骤占 39.8% 步骤分”论证放置的杠杆。**终局放置仍然是 32/32 任务的成功闸门，这个结论不变；但“步骤分占 60%”不再是和成功率并列的权重，只是同分裁决。** 因此：

1. 任何会降低成功率的“刷步骤分”都不划算；
2. 恢复决策必须是**字典序**：先最大化成功率，成功率无望时才最大化步骤分；
3. 资源应从“把某一步的分数抠高”转向“把失败 episode 转成成功 episode”；
4. 第 7 轮的放置模块（SSG/PGL/OPT/SVL）保留，但它只是执行层的一个子模块，不再是全部。

### 0.2 数据与榜单的复核

- 排行榜仍然是 **Coming Soon**；`leaderboard_data.json` 仍是 `generated_from: gen_leaderboard.py` 的占位数据，`runs.html` 也仍是占位（[S6][S7]）。所以“榜首成功率不到 30%”目前只能作为用户给定/待核实的外部信息，不能从官网独立核验；占位榜的数字只能当难度先验，不能做轴级归因。

### 0.3 统计功效：320 次听起来多，其实只够分辨大效应

按二项分布粗算（p≈0.3）：

| 粒度 | 样本数 | 成功率标准误 | 含义 |
|---|---:|---:|---|
| 总榜 | 320 | ≈2.6pp | 30% 的 95% CI 约 ±5pp |
| 单轴（5 轴之一） | 32 任务 ×2 = 64 | ≈5.7pp | 轴级差异很容易是噪声 |
| 单任务 | 10 | ≈14.5pp | 不要用单任务输赢判断方案 |

这意味着两件事：

- **+3pp 的“小改进”在这个榜单上几乎不可证伪**；要押就押 +8–10pp 量级、跨任务一致的改进。
- 轴级结论必须用配对调试槽（同一任务、同一初始条件、A/B）或离线大量配对样本来支撑，不能只看正式跑的分轴数字。

第 7 轮曾写“+3pp 约 80% 概率排名更高”，这个说法本轮撤回：在 320 次、两次独立跑之间，+3pp 只有约 0.83 个标准误，远达不到 80% 把握。**恢复层如果只能带来 +2–3pp，就不值得作为主押注；它必须瞄准 +10pp 量级。**

## 1. 三个灵感词，各自钉到官方结构与 2026 年证据上

### 1.1 场景泛化：五个轴不是五种数据增强，而是五种失败机制

官方把泛化拆成 5 类、每类 2 次（[S1] §2.1）。第 7 轮已经抓过逐任务备注（[S8]），本轮把它们重新按“失败机制”而不是“数据分布”来读：

| 官方轴 | 表面变化 | 真正打中的能力缺口 | 典型失败 |
|---|---|---|---|
| 位置 | 目标/容器初始位置或目标区域平移 | 绝对坐标记忆、抓取/放置点 grounding | 抓空、放偏、路径撞到别的东西 |
| 干扰物 | 场景里多出无关物体 | 目标绑定、遮挡、碰撞 | 抓错实例、被杂物挡住、运输碰撞 |
| 桌面背景 | 桌布颜色/纹理变化 | 全局外观 shortcut、背景纠缠 | 视觉编码漂移、检测/分割失效 |
| 未见物品 | 同类但颜色/形状/材质不同 | 类别级几何/功能理解 | 不会抓新形状、放不进容器 |
| 人为干扰 | 执行中移动物体、撤销已完成步骤 | **非单调进度**、在线重规划 | 继续按旧计划做、不知道步骤被撤销 |

这张表的关键推论：**场景泛化的核心不是“再采一批背景图”，而是两件事——(a) 任务相关关系状态的不变性；(b) 进度信念的可逆性。** 前者对付位置/干扰物/背景/未见物品，后者专门对付人为干扰里的“先叠后撤”“拉上再拉开”“拧开再拧回”。

证据链是够的：

- **Spa-Bench**（[S11]）显示真机 OOD 空间 grounding 是主要瓶颈：ID 67.5–73.3% → OOD 40.7–52.0%；把空间指令换成直接操作指令可 +28–40pp。说明“关系/空间 grounding”比“动作执行”更缺。
- **SOCR / Slot-based Object-Centric Representations**（[S12]）在 MetaWorld、LIBERO 和真机上系统比较 global/dense/object-centric 表征，object-centric 在光照、纹理、clutter 漂移下显著更稳；DINOSAUR-Rob* 在真机 shift 下平均 41%，远高于 dense/global。说明“把场景拆成物体槽”是对付背景/干扰物的正路。
- **TriRelVLA**（[S13]）把 object–hand–task 三元关系做成显式图，跨场景/跨物体/跨任务都有增益；**KeyGen**（[S14]）用类别级 3D 关键点做实例迁移；**Mind-VLA**（[S15]）做指令感知的目标物体 3D 对齐，在目标遮挡真机任务上 54% vs 匹配场景控制的 26%。这些都在说：**要建模“目标—手—容器—桌面”的关系，而不是整张图的 appearance。**
- **Scene graph as memory**（[S16]）把动态场景图当长时记忆，专门解决部分可观测和长程任务；**UniManip**（[S17]）用 object-centric scene graph + agentic loop 做零样本操作和失败恢复，比 SOTA VLA 高 22.5pp；**LiLo-VLA**（[S18]）把 transport 与 interaction 解耦，用 object-centric VLA 做长程组合，仿真 69% vs Pi0.5 41%，真机 85%，并且模块化天然支持 replanning。这些说明“关系图 + 模块化”不仅能泛化，也能承接恢复。

所以场景泛化不是独立的一条研究线，它天然是恢复器的**输入层**：如果状态表征本身对五轴不变，失败诊断才有跨轴的可迁移性。

### 1.2 失败恢复：2026 年已经从“重试”进化到“诊断 → 路由 → 干预”

2026 年下半年的恢复论文密度非常高，而且结论开始互相校正：

- **FLARE**（[S19]）提出 Retry/Reset 两段式：用扰动 + bridging segment 让策略学会从偏移状态继续；对 OOD 失败用 MLLM 离线分析失败视频，采一小库 object-centric reset 技能，在线 MLLM monitor 在任务执行与 reset 之间仲裁。
- **VLA-Corrector**（[S20]）用 observable-history verifier 联合估计进度与风险，把执行分成 approach/alignment/grasp/transport/placement 五阶段，检测异常后生成 stage-conditioned recovery prompt，让**冻结的 VLA** 自己纠正；不需要特权坐标，效果接近有特权状态的规则 verifier。
- **CARE**（[S21]）收集真实失败 rollout，建 stage-conditioned 失败分布，合成失败状态与纠正演示；推理时 stage-wise planning + 3D monitoring，触发 atomic adjustment 或 re-operation；仿真 +14.5pp、真机 +15.9pp，并发布 FSR-Bench。
- **LIBERO-Recover**（[S22]）用 2,000+ 真实失败场景分四级（Action Retry / Action Adaptation / Object State Recovery / Environmental Recovery），发现所有模型在失败后性能断崖：例如 LIBERO-100 从 26.2% 掉到 0.3%，说明失败会引发**复合分布偏移**，不是一次重试就能回去。
- **Backtrack**（[S23]）只加一个 0.48–0.88% 参数的 failure prediction head，读冻结 VLA 的内部特征预测本 episode 是否会失败；超过阈值就让机械臂沿最近轨迹倒退，再把控制权交回原策略；LIBERO-Long 成功率最高 +7.4pp，且不需要恢复演示或第二个模型。
- **FIT-MAC**（[S24]）把失败分成 **target-binding error** 与 **local execution failure** 两类：前者重新 grounding，后者用 bounded pick/place recovery；Planner/Grounder/Verifier/Correction 四个 agent 协同，在 LIBERO-PRO 上跨 VLA backbone 提升。
- **RESCUE**（[S25]）给了一个很重要的冷水：**失败检测准确 ≠ 干预有价值**。它用 128,340 条反事实分支评估 runtime monitor，发现“报警太晚无法恢复”与“没必要干预却打断了一个本来会成功的 episode”同样致命；在 stop-and-reset 模型下，即使理想检测器也只能承受 **2.0–3.3% 的误报率**，否则 reset 的破坏大于收益。
- **“Does a Learned Corrector Beat a Simple Retreat?”**（[S26]）进一步用 3,888 对 episode 做 placebo 对照：学习式 correction 只在 4 个 RoboTwin 任务里的 1 个显著有效（+13.5pp）；失败 episode 的普通重跑本身就有 43.2% 成功率，学习式 correction 是 63.5%，净增益只有 +20.4pp；一个固定时间触发的脚本化 retreat 与完整学习管线在统计上无法区分。结论：**先证明恢复比“什么都不做/简单回退”好，再谈复杂模块。**
- **SO-101 failure/recovery benchmark**（[S27]）测了 ACT/SmolVLA/Wall-X/π0.5，恢复率只有 3.23%–30.77%，执行不稳定是主要失败源；恢复能力在不同架构间差异巨大，单看成功率会漏掉关键差异。

这几篇合起来，给 UniBot 的启示非常明确：

1. **失败检测只是第一步，干预决策才是价值所在。** 需要一个“不干预”选项和严格的触发阈值。
2. **失败类型决定恢复方式。** 目标绑定错、抓空、滑落、碰撞、插入失败、步骤被撤销，不能用同一个 retry。
3. **简单回退/重跑是很强的基线。** 任何复杂恢复模块必须在 placebo 对照下证明净增益。
4. **失败后的分布偏移会复合。** 恢复器需要把状态带回“策略熟悉”的流形，而不是在越来越陌生的状态里连续试错。
5. **现有工作大多没有预算概念。** 它们优化“最终成功率”，但 UniBot 每次只有 180 秒，且要跨 32 个任务共享一个模型；什么时候救、救多久、何时放弃，是一个独立的决策问题。

### 1.3 决策规划：在 180 秒内，恢复是一个带预算的停止/调度问题

官方给的是硬约束：单次 180 秒，超时即失败（[S1]）。所以恢复不是“无限重试”，而是一个**有限时间预算下的序贯决策**：

- 状态：当前步骤 i、失败模式 m、剩余时间 τ、已完成的步骤集合、失败历史。
- 动作：继续、重观察、重定位、重接近、重抓、复位物体、回退、缓放、插入搜索、重做步骤、重同步、放弃并转下一步。
- 每个动作有**时间成本 c(a)**、**成功概率 p(a|s)**、**失败后的后续状态**。
- 目标不是单一的“任务成功”，而是字典序：先最大化 P(全部步骤完成)，再最大化步骤分（同分裁决），同时不能超过 180 秒。

这和 2026 年几篇“元推理/测试时算力”的工作是同一个结构：

- **RESCUE**（[S25]）把 monitor 的价值定义为“从报警检查点出发，现有干预集合能否在剩余预算内完成任务”，并引入 recoverability horizon——这正是预算化恢复的价值函数。
- **ForkCast**（[S28]）在冻结 VLA 上比较 Commit / Reobserve / Replan 三个候选，用 candidate-conditioned world model 预测每个候选的未来，再用 progress head 打分；在 RoboTwin 2.0 的遮挡/滑落注入下把 pooled success 从 13.3% 提到 30.0%，且无需 failure detector 或阈值。它证明“比较反事实未来”可以作为干预决策器。
- **Agentic RL for robust execution**（[S29]）让高层 agent 观察执行历史，在一小组 execution modes 里选择，触发恢复机制把机器人带回之前访问过的 nominal state；标准设置 +13.7pp、扰动设置 +39.2pp。它证明“高层选模式”比“低层直接学恢复动作”更有效。
- **ELASTIC**（[S30]）把测试时算力分配建模成 meta-MDP，让 meta-policy 与冻结策略交互，在成功率和算力之间做权衡；**Learning Robot Metareasoning**（[S31]）也把“规划多久再执行”当成可学习的预算分配。这些为“何时多想、何时直接做”提供了方法论。
- **B2FF**（[S32]）用预先想象的 milestone bank 做恢复，失败注入 LIBERO 上 56.3%→74.0%；**CoRe**（[S33]）用反事实 continuation 做 training-free realignment，最高 +85pp；**CycleVLA**（[S34]）用 subtask backtracking + MBR decoding 做 proactive self-correction。这些说明“回到一个熟悉的未来/过去状态”是恢复的有效接口。

但现有工作普遍缺三个东西，恰好是 UniBot 的结构能提供的：

1. **公开的步骤图与权重**：可以显式定义“当前步骤、完成谓词、依赖关系、每步分值”，从而做步骤级预算分配。
2. **五轴 ×2 的评测结构**：可以把失败诊断与场景泛化轴对齐，而不是在单一分布上做恢复。
3. **单模型 + 远程 API + 180 秒**：可以把它做成一个**单 checkpoint 的执行层**，而不是多模型 agent 拼装；这对规则合规和延迟都更友好。

## 2. 本轮主判断：从“放置优先”升级为“执行层优先”

### 2.1 一个更锋利的失败算术

把任务近似成 K 个串联步骤，每步首次成功率 p；恢复机制把失败的一部分比例 r 转成成功（一次重试，重试成功率近似仍为 p），则有效步骤成功率：

```text
p' = p + r · p · (1 − p)
任务成功率 ≈ (p')^K
```

用这个一阶模型算几个点（不是承诺，只是数量级）：

| 每步首次成功率 p | 步数 K | 无恢复 | r=0.3 | r=0.5 |
|---:|---:|---:|---:|---:|
| 0.70 | 4 | 24.0% | 33.9% (+9.9pp) | 42.0% (+18.0pp) |
| 0.75 | 4 | 31.6% | 42.3% (+10.6pp) | 50.7% (+19.0pp) |
| 0.80 | 4 | 41.0% | 51.7% (+10.8pp) | 60.0% (+19.0pp) |
| 0.75 | 5 | 23.7% | 34.1% (+10.3pp) | 42.8% (+19.0pp) |

如果榜首确实不到 30%，那么每步首次成功率大概率在 0.65–0.8、K 在 2–5 之间；**恢复率 r 从 0.2–0.3 提到 0.5，就可能带来 10–20pp 的任务成功率**。这比在单个泛化轴上抠 2–3pp 更符合 320 次评测的统计功效，也更符合“失败是常态”的现实。

### 2.2 为什么不是继续只攻终局放置

第 7 轮的论证仍然成立：终局放置是 32/32 任务的成功闸门，且跨五轴。但它有两个边界：

- 终局放置只覆盖“已经走到最后一步”的 episode；如果模型在抓取、运输、开盖、拉拉链等中途失败，终局模块根本用不上。
- 终局放置的收益上限是 P(到达终局) × Δ；恢复的收益上限是“所有步骤的失败 mass × 可恢复比例”，在低成功率区间通常更大。

更准确地说，二者不是替代关系，而是**串联**：

```text
成功率 = P(走到终局) × P(终局成功 | 走到终局)
          ↑ 恢复层的主战场        ↑ 放置模块的主战场
```

第 7 轮把第二项做深；第 8 轮要把第一项做深，并且让恢复层也能救第二项的失败（例如放置后掉落、插入不到位、被人类拔起）。

### 2.3 三个词的合流：TRIAGE

我把本轮的方案叫 **TRIAGE**（Task-agnostic Recovery with Invariant scene Assessment and Gated Execution）——名字取“分诊”之意：不是所有失败都值得救，先诊断、再路由、再按预算决定。

六个组件：

1. **SIR（Scene-Invariant Relational state）**：从四路 RGB + 本体状态 + 语言，维护“目标—手—容器—桌面”的关系图与物体轨迹；用 object-centric slot / 类别级关键点 / 相对位姿，抗位置、干扰物、背景、未见物品。
2. **RSB（Reversible Stage Belief）**：把官方 `score_steps` 变成带谓词的步骤图；进度信念允许 `1→0`（被人类撤销/物体被移走），不是单调计数器。
3. **FMR（Failure Mode Router）**：把失败分成 9 类（目标绑定错、目标被移动、抓空/滑落、运输碰撞/遮挡、放置/插入失败、完成后被撤销、复合漂移、双臂失同步、预算耗尽），输出失败模式分布。
4. **ROL（Recovery Operator Library）**：一小组任务无关的恢复动作：继续、重观察、重定位、重接近、重抓、复位物体、回退、缓放、插入搜索、重做步骤、重同步、放弃并转下一步（12 个，含 CONTINUE）。
5. **BRS（Budgeted Recovery Scheduler）**：在 180 秒内做半马尔可夫决策/最优停止；先最大化成功率，再最大化步骤分；有“不干预”选项和严格误触发阈值。
6. **ARD（Axis-Randomized failure Data）**：用官方 5 轴 + human 备注 + 执行扰动，合成失败状态与恢复对；再用反事实 rollout 给每个算子打标签，训练 FMR/BRS。

**关键设计约束：所有这些学习组件必须在同一个 checkpoint 里。** 规则不允许混合多个模型；所以 SIR/FMR/BRS 都是 WLA 主干上的头，ROL 是确定性代码，推理时不调用外部 VLM/SAM。这样既合规，也能把延迟压在可接受范围。

### 2.4 与现有方案的差异

| 方案 | 诊断 | 恢复算子 | 预算/停止 | 步骤图 | 场景轴 | 单模型 |
|---|---|---|---|---|---|---|
| FLARE | MLLM monitor | Retry/Reset | 无 | 无 | 无 | 否（外部 MLLM） |
| VLA-Corrector | stage verifier | prompt recovery | 无 | 五阶段 | 无 | 基本是（冻结 VLA） |
| CARE | 3D monitor | atomic correction | 无 | stage-wise | 无 | 否（多模块） |
| Backtrack | failure head | retrace | 无 | 无 | 无 | 是（小头） |
| FIT-MAC | verifier agent | target rebind / bounded recovery | 无 | 阶段 | 部分 | 否（多 agent） |
| RESCUE | monitor 评估 | 反事实干预 | 有（评估框架） | 无 | 无 | 不适用 |
| ForkCast | world model | Commit/Reobserve/Replan | 无 | 无 | 无 | 基本是（冻结 VLA） |
| UniManip | scene graph | agentic loop | 无 | 操作图 | 部分 | 否（VLM planner） |
| **TRIAGE** | **SIR + RSB + FMR** | **12 个动作（含 CONTINUE）** | **半马尔可夫/阈值** | **官方 score_steps** | **5 轴对齐** | **是（单 checkpoint）** |

差异的核心不是“再加一个恢复模块”，而是把恢复变成一个**可计算的调度问题**：给定公开步骤图、剩余时间和失败模式，选择期望成功率增益/秒最大的算子；当增益不够或误触发风险太高时，**明确选择不干预**。

## 3. 为什么现在做、为什么由我们做

- **现在做**：2026 年下半年恢复论文密集出现（FLARE、VLA-Corrector、CARE、Backtrack、FIT-MAC、RESCUE、ForkCast），说明问题被验证；但大多数还停留在“检测 + 固定干预”或“仿真 benchmark”，没有把预算、步骤图、五轴泛化和单模型约束放在一起。UniBot 恰好提供了这个组合。
- **由我们做**：第 5–7 轮已经积累了 SSG 步骤图、PGL 放置目标、OPT 位姿迁移、SVL 落点闭环、NRB 备注恢复库、TLE/ACP 数据引擎。TRIAGE 不是推倒重来，而是把这些模块重新组织到“执行层”下：SSG → RSB，NRB → ARD，SVL → ROL 的 settle 算子，PGL/OPT 保留为终局放置子模块。
- **可证伪**：如果 TRIAGE 在配对调试槽上不能带来 ≥5pp 的净增益（相对 no-intervention / 简单 backtrack），或者误干预率 >5%，就回退到“SSG + 简单 backtrack + settle”的最小版本，不把复杂调度器带进正式跑。

## 4. 本轮主动修剪的东西

- **ICR（检索上下文条件化）降级**：它在第 7 轮是主押注之一，但检索不直接解决“失败后怎么办”，且 26 万段缓存 + 检索延迟 + 训练期注入会显著增加工程复杂度。本轮把它降为“PGL/OPT 的可选上下文”，不再作为主线。
- **L2L（产学研数据协议）降级**：官方规则只明确给 32 任务数据，外部数据/合作数据是否允许仍未确认；在成功率优先的排名下，场景多样性可以用官方数据的合成编辑先顶，L2L 转为赛后/合规确认后的补充。
- **全 32 任务高保真孪生砍掉**：恢复数据的反事实 rollout 只需要“失败状态 + 算子结果”，不需要全物理高保真；用 2.5D 编辑 + 回放 + 少量真机调试槽即可。
- **复杂世界模型不进主路径**：ForkCast 式的 candidate-conditioned world model 很有吸引力，但本轮只把它作为 BRS 的可选值估计器（ablation），主路径先用“校准过的轻量 value head + 规则先验”，避免算力和合规风险。
- **不做每任务 LoRA / 多模型融合**：单模型规则 + 32 任务共享，恢复层必须任务无关。

## 5. 一句话押注

**在成功率优先、5 轴各 2 次、180 秒的 UniBot 里，最大的边际收益来自“失败后的执行层”：用场景不变的关系状态做诊断，用少量恢复算子做路由，用预算化调度决定“救 / 不救 / 换步”，把失败 episode 的恢复收益做成跨五轴的系统性增益；终局放置模块保留，但它只是这个执行层的一个子模块。**

## 1. 事实核对（本轮新增/复核，全部一手）

### 1.1 官方参赛手册：评测结构与排名规则

来源：挑战赛页面挂出的中文/英文参赛手册（Feishu 文档，[S1][S2]）。关键条款原文/转述：

1. **通才模型赛道**：提交一个模型完成全部 32 个任务；每个任务在不同泛化场景中 **10 次测试**；计算每个任务的平均成功率、平均过程分（步骤分），计入排行榜。
2. **10 次 = 5 类泛化 × 每类 2 次**：位置、干扰物、桌面背景、未见物品、人为干扰。
3. **排名**：按 32 个任务的 **总平均成功率** 排序；成功率相同按 **总平均步骤分**；仍相同则 **提交日期更早** 的模型靠前。
4. **单次最长 180 秒**；超时记为失败，并按执行情况计算步骤分。
5. **单模型**：所有任务必须基于同一模型完成，不得混合多个模型一起测试；模型类型不限（World Model、VLA 均可）。
6. **自部署 + 远程 API**：官方只做远程调用，不托管模型；模型需稳定在线推理。
7. **单任务调试通道**：可单独测 1 个任务，成功率/步骤分不计入排行榜（[S2] §1.2；[S3]）。

其中排名条款的原文是：「实时榜单按32个任务的总平均成功率进行排序，成功率相同时按总平均步骤分排序，若仍相同，则提交日期较早的模型排序靠前。」（[S1] §1.2）

由 1–3 可得总评测量 **32 × 10 = 320 次真机 episode**；每个轴 32 × 2 = 64 次；每个任务 10 次。

## 2. 评分算术：为什么恢复层的杠杆更大

### 2.1 官方排名是字典序

```text
rank_key = (avg_success, avg_step_score, submission_date)
avg_success = (1/32) Σ_t (1/10) Σ_{r=1..10} 1[success_{t,r}]
avg_step_score = (1/32) Σ_t (1/10) Σ_r step_score_{t,r}
```

每个任务的 10 次覆盖 5 轴 ×2。因此：

- 一个 **全任务、全轴** 的 +Δ 成功率改进 → 总榜约 +Δ。
- 一个只作用于 **单轴** 的 +Δ → 总榜约 +Δ/5（因为该轴只占 1/5 的 run）。
- 终局放置改进 +Δ_tp → 总榜约 +Δ_tp × P(到达终局)。
- 恢复改进 +Δ_rec → 总榜约 +Δ_rec × P(发生可恢复失败)。

在低成功率区间，`P(发生可恢复失败)` 往往大于 `P(到达终局)`，所以恢复的边际收益更大；但它也更难做，因为需要诊断、算子、预算三件事同时正确。

### 2.2 步骤分只做同分裁决

第 7 轮把步骤分当作与成功率并列的“大头”，本轮修正：

- 步骤分只在成功率相同的时候决定排名；它不是主目标。
- 但在两种情况下仍然有用：(a) 成功率打平（320 次、粒度 0.3125%，完全可能）；(b) 一个 episode 已经确定无法成功时，继续完成独立步骤可以刷步骤分，且不损害成功率。
- 因此 BRS 的目标是字典序：`max P(success)`，在 `P(success)` 相同的解里 `max E[step_score]`，再 `min E[time]`。不要为了步骤分牺牲成功概率。

### 2.3 失败算术：恢复是乘数

把任务近似为 K 个串联步骤，每步首次成功率 p；恢复把失败比例 r 转成成功（一次重试，重试成功率近似 p），则：

```text
p' = p + r · p · (1 − p)
P(task success) ≈ (p')^K
```

| p | K | r=0 | r=0.3 | r=0.5 |
|---:|---:|---:|---:|---:|
| 0.70 | 4 | 24.0% | 33.9% (+9.9pp) | 42.0% (+18.0pp) |
| 0.75 | 4 | 31.6% | 42.3% (+10.6pp) | 50.7% (+19.0pp) |
| 0.80 | 4 | 41.0% | 51.7% (+10.8pp) | 60.0% (+19.0pp) |
| 0.75 | 5 | 23.7% | 34.1% (+10.3pp) | 42.8% (+19.0pp) |
| 0.80 | 5 | 32.8% | 43.9% (+11.1pp) | 52.8% (+20.0pp) |

这是独立步骤的一阶近似；真实任务有依赖、恢复成本、恢复后的分布偏移，收益会打折。但它说明：**在 p≈0.75、K≈4 的区间，恢复率从 0.2 提到 0.5 的收益是 10–20pp 量级，足以穿过 320 次评测的噪声。**

### 2.4 统计功效：不要用小效应讲故事

| 粒度 | n | p=0.3 时 SE | 95% CI 半宽 |
|---|---:|---:|---:|
| 总榜 | 320 | 2.56pp | ±5.0pp |
| 单轴 | 64 | 5.73pp | ±11.2pp |
| 单任务 | 10 | 14.49pp | ±28.4pp |

两次独立 320 次跑的差值 SE ≈ 3.62pp；+5pp 只有 1.38 SE，+3pp 只有 0.83 SE。**结论：正式榜只能可靠分辨 +8–10pp 量级；轴级/任务级差异必须用配对调试槽或离线配对实验。** 这也是为什么恢复层必须瞄准大效应，而不是 +2pp 的小修小补。

### 2.5 时间预算

- 单次 180s；数据中 HangCup episode 中位约 5.9s（94–411 帧，30fps），说明正常执行远低于 180s，恢复预算充足。
- 但长程任务（T16/T17/T31，4–5 步）和遮挡/重抓会拉长时间；BRS 要给剩余步骤预留时间，不能把 180s 全花在第一步。
- 建议每个 episode 的恢复预算上限：短任务 ≤60s，长任务 ≤90s；剩余时间低于 30s 时，只允许低风险算子（settle/backtrack/reobserve），不允许 reset/redo。

### 4.2 SIR：场景不变关系状态

**目标**：给 FMR/BRS 一个对五轴都尽量不变的状态，而不是原始像素。

**输入**：四路 RGB、双臂关节/EE 位姿、夹爪开度、下半身、语言指令、最近 T 帧历史。

**结构**：

1. **视觉 token 共享**：复用 VLA 主干的视觉编码器，避免引入第二个视觉模型；四路图像各自 token 化，带相机 ID/外参嵌入。
2. **物体槽（slot attention）**：N=16–32 个槽，每个槽输出 `(appearance, 3D position, category embedding, visibility, track_id)`；位置由单目深度头或 EE-relative 几何回归得到，不要求外部深度模型。
3. **关系图**：节点 = 物体槽 + 左右夹爪 + 容器 + 桌面/架子；边 = 相对位姿、接触、容纳（in/on）、支撑、遮挡、可见性。用 2–4 层 graph transformer 更新。
4. **时序记忆**：对最近 T=8–16 帧的图 token 做轻量时序注意力/GRU，输出物体轨迹与谓词状态；用 track_id 维持跨帧一致。
5. **输出** `b_t`：
   - 物体轨迹与相对位姿（任务坐标系，建议 base 或桌面系）；
   - 接触/夹持/容纳/稳定谓词；
   - 当前步骤后验 `s_t`（与 RSB 共享）；
   - 失败模式后验 `m_t`（与 FMR 共享）；
   - 可见性/遮挡图。

**不变性训练**：

- 正样本对：同一任务/同一阶段，背景替换、光照变化、干扰物插入、目标换色/换形状（类别内）。
- 负样本对：不同任务/不同阶段/不同关系。
- 对比损失作用在关系图 embedding 上；辅助损失监督相对位姿、接触/容纳谓词。
- 目标不是“识别物体类别”，而是“保持任务相关关系不变”；外观只作为类别/实例的弱线索。

**为什么不用 SAM/DINO 常驻**：单模型合规 + 延迟。可以离线用教师模型蒸馏到 SIR 头，但推理时只跑单 checkpoint；教师模型只在训练期出现，需在模型卡披露并确认规则允许。

### 4.3 RSB：可逆步骤信念

**输入**：SSG 的步骤图 + SIR 的谓词后验。

**步骤图**：

- 每个任务 `t` 有步骤 `i=1..K_t`，权重 `w_i`（官方分值），依赖边 `i → j`（例如必须先抓再放）。
- 独立步骤用并行分支表示（例如 T15 的 4 个工具、T02 的 2 个水果）；这样 F9/BANK 才能选择“转步”。
- 每个步骤有完成谓词 `g_i`（如 `object_in_container`, `gripper_closed`, `lid_closed`, `zipper_closed`, `plug_inserted`）。

**可逆 HMM**：

```text
b_i(t) = P(current step = i | o_{1:t})
转移：i → i+1（正常完成）
      i → i-1（检测到回归/撤销）
      i → i（继续）
观测：谓词 g_i 的伯努利/多类后验
```

关键：**允许 `1→0`**。完成谓词从高置信 1 掉到 0 并持续 k 帧（k=3–5），触发 F6「完成后被撤销」，把 `b` 回退到受影响步骤；不是单调计数器。

伪代码：

```python
def update_stage(prev_b, preds, cfg):
    # preds: {step_i: P(g_i=1 | obs)}
    b = prev_b.copy()
    for i in range(K):
        # 正常前进：当前步谓词高置信，且下一步谓词开始上升
        if preds[i] > cfg.enter and b[i] > 0.5:
            b[i+1] += cfg.forward_gain * b[i]
        # 回归：已完成谓词掉下去（人为撤销/物体被移走）
        if prev_preds[i] > cfg.exit_high and preds[i] < cfg.exit_low:
            b[i-1] += cfg.back_gain * b[i]
            b[i] *= cfg.regress_decay
    return normalize(b)
```

`enter/exit` 用双阈值滞回，避免抖动；回归事件单独输出给 FMR/BRS。

### 4.4 ROL：恢复算子库

每个算子是一个短宏动作（脚本化 waypoint / 同 checkpoint 的条件推理），有前置条件、时间成本、风险等级。**不是新模型**。

| 算子 | 前置条件 | 动作 | 典型时间 | 风险 |
|---|---|---|---:|---|
| CONTINUE | 无 | 调原策略，发 chunk | 0.1–1s/chunk | 低 |
| REOBSERVE | 目标/关系不确定 | 腕/头相机移动到观察位，重跑 SIR/FMR | 1–3s | 低 |
| REGROUND | F1/F2/F6 | 用指令 + 关系图重新绑定目标实例；更新内部 context | <0.5s | 低 |
| REAPPROACH | F2/F4/F5 | 沿接近向量后退 5–10cm，重新对齐，半速接近 | 2–6s | 中 |
| REGRASP | F3 | 开爪→后退→旋转 ±30–90°→重接近→闭合；最多 2 次 | 5–12s | 中 |
| RESET_OBJECT | F3/F7，物体掉落/翻倒 | 脚本化推/扶/重抓放到规范位姿；只对已建模物体 | 10–25s | 高 |
| BACKTRACK | F7 | 反向回放最近 N 个 EE waypoint，回到策略熟悉的流形 | 2–8s | 中 |
| SETTLE | F5 | 缓放→等 0.5s→稳定性/谓词校验→微调 | 1–3s | 低 |
| RETRY_INSERT | F5 | 在插入点做小范围搜索（圆/锯齿），逐步加深；无力觉时用视觉 | 3–10s | 中 |
| REDO_STEP | F6/F7 | 回到该步骤起始位姿（演示/OPT），重执行 | 5–20s | 中 |
| RESYNC | F8 | 双臂回到演示相对位姿，慢速重新同步 | 3–8s | 中 |
| BANK_ADVANCE | F9/成功无望 | 跳到下一个独立步骤，完成它拿步骤分 | 取决于步骤 | 低 |

实现要点：

- 所有算子输出统一的 `action` 字典（joint 或 ee 二选一），走同一个 `get_action` 接口。
- 算子内部可以调用同一个 checkpoint 的 policy（例如 REGRASP 用条件 prompt 生成动作），但不能调用第二个模型。
- RESET_OBJECT 只对已建模的刚体/容器实现；布料/拉链/透明物体回退到 REDO_STEP/BACKTRACK。
- 每个算子有 `max_calls` 和 `timeout`，由 BRS 管。

### 4.5 FMR：失败模式路由

**输入**：`b_t`（SIR 关系图 + RSB 阶段后验 + 最近动作/EE 轨迹）。

**输出**：9 类失败模式的后验 `m_t`（F1–F9）。

**训练标签来源**：

1. **合成轴扰动**：位置/干扰物/背景/未见物品/执行扰动，已知注入的失败类型。
2. **官方 human 备注**：F6/F2 的剧本。
3. **真实失败 rollout**：在调试槽/仿真里跑 base policy，收集失败，用规则 + 离线 MLLM 标注（MLLM 只在训练期，推理不用）。
4. **自然恢复片段**：从 33k 成功演示里挖“重抓/回退/重试”片段，弱标签。

**校准**：温度缩放 + 混淆矩阵；FMR 的输出不是最终动作，而是给 BRS 剪枝候选算子。误分类的代价由 BRS 的“不干预”阈值兜底。

**路由先验**：§3.2 表；FMR 后验与规则先验相乘/加权，避免小数据过拟合。

### 4.6 BRS：预算化恢复调度

#### 4.6.1 形式化

半马尔可夫决策过程：

```text
状态 s = (i, m, τ, h, c)
  i: 当前步骤（RSB）
  m: 失败模式（FMR）
  τ: 剩余时间
  h: 最近算子历史（防止死循环）
  c: 已完成步骤集合/步骤分
动作 a ∈ A(s) = {CONTINUE} ∪ ROL.candidates(m, b)
  c(a): 时间成本（标定表 + 不确定性）
  p(a|s): 算子成功概率（BRS 值头）
转移:
  success → (i+1, m', τ-c, h∪a, c+w_i)
  fail    → (i or i-1, m'', τ-c, h∪a, c)
奖励:
  R = 1[全部步骤完成]  (主)
      + ε · step_score   (次，同分裁决)
      − λ · time         (小惩罚)
目标:
  lexicographic max (P(success), E[step_score], −E[time])
```

#### 4.6.2 一步阈值规则（可解释、可先上线）

对每个候选算子 `a`，估计：

```text
Q(s,a) = p_a · V_succ(s') + (1-p_a) · V_fail(s'') − λ · c_a
```

其中 `V_succ` 是完成后剩余步骤的价值，`V_fail` 是失败后的回退价值。选择：

```text
a* = argmax_a Q(s,a)
if Q(s,a*) − Q(s,CONTINUE) < δ: 不干预
if c_a > τ − τ_reserve:          该算子不可用
```

`δ` 是干预阈值；用调试槽/离线配对数据校准到**误干预率 ≤5%**（reset 类算子建议 ≤2–3%，参考 RESCUE 的 2.0–3.3% 结论）。

#### 4.6.3 时间影子价格

`λ` 可以粗略设为“剩余时间内每秒钟的平均成功价值”：

```text
λ ≈ (V_remaining_success − V_current) / (τ − τ_reserve)
```

直观解释：如果一个算子花 20s 只把成功率从 0.30 提到 0.32，而同样的 20s 可以用来完成一个独立步骤拿 30 分步骤分（在同分裁决下有价值），那么它可能不值得。BRS 用 `λ` 把时间折算成价值，避免“为了 1% 成功率把 180s 全花掉”。

#### 4.6.4 失败无望时的转步

如果 `P(success | s) < ε`（例如当前步依赖链已断），BRS 切换到 **BANK_ADVANCE**：

- 在步骤图上找下一个“独立且未完成”的步骤；
- 用剩余时间完成它，拿步骤分；
- 不尝试 reset/redo 依赖链，因为成功已不可能，重试只浪费时间。

注意：官方规则说“直至任务成功、失败或超时”，如果评测器在失败时立即终止 episode，BANK_ADVANCE 可能没有机会执行；这是一个开放问题（§12）。如果 episode 会继续到超时，BANK_ADVANCE 才有意义。

#### 4.6.5 伪代码

```python
class TRIAGE:
    def act(self, obs, tau):
        b = self.sir(obs, self.history)
        s = self.rsb.update(b, self.prev_preds)
        m = self.fmr(b, s, self.history)

        if not self.should_check(b, m, s):
            a = self.policy.act(obs)          # CONTINUE
            self.history.append(("continue", a, b))
            return a

        ops = self.rol.candidates(m, b, s)
        qs = {op: self.brs.value(b, s, op, tau) for op in ops}
        qs["CONTINUE"] = self.brs.value(b, s, "CONTINUE", tau)

        best = max(qs, key=lambda k: qs[k].lex_key())
        if qs[best].success - qs["CONTINUE"].success < self.delta:
            a = self.policy.act(obs)          # 不干预
        elif qs[best].cost > tau - self.reserve:
            a = self.policy.act(obs)          # 时间不够，保守
        else:
            a = self.rol.execute(best, b, s)

        self.history.append((best, a, b))
        return a
```

### 4.7 单 checkpoint 集成

**主干**：WLA-1.0-Base（6B，Apache-2.0，24GB 可微调，[S38]）或同量级 VLA；动作专家输出 chunk。

**头**：

| 头 | 输出 | 参数量级 | 训练信号 |
|---|---|---:|---|
| 动作专家 | action chunk | 主干一部分 | 行为克隆/flow matching |
| SIR 头 | 槽/关系图/相对位姿/可见性 | 50–150M | 关系/位姿辅助 + 对比 |
| RSB 头 | 每步谓词后验 | 5–20M | 步骤标签/谓词 BCE |
| FMR 头 | 9 类失败后验 | 5–20M | 合成/真实失败标签 |
| BRS 值头 | 每个候选算子的 `(p_success, cost)` | 5–20M | 反事实 rollout 标签 |

**合规**：

- 所有学习组件在同一个 checkpoint；推理只加载一个权重文件。
- ROL 是确定性代码（waypoint、gripper、慢速释放等），不是模型。
- 不在推理时调用外部 VLM/SAM/检测器；如离线用教师模型蒸馏，需在模型卡披露，并确认规则允许。
- `metadata` 只声明实际需要的观测 key；图像 resize/堆叠在接口内完成。

**延迟**：

- SIR/RSB/FMR 与动作共享一次前向；BRS 只对 2–4 个候选做小 MLP 打分；目标 `get_action` p99 <100ms。
- 重观察/重抓等算子会多次调用 `get_action`，但每次仍是同一 checkpoint；BRS 限制总恢复时间。

### 4.8 与 GPR-VLA 的接口

第 7 轮的 GPR-VLA 是“目标残差 + 可逆信念 + 动作专家”。本轮把它作为 `CONTINUE` 和算子内部的动作生成器：

- SIR 的关系图/目标锚点 → GPR 的目标 `z*`；
- RSB 的阶段 → GPR 的步骤条件；
- FMR/BRS → 选择算子/是否干预；
- SVL → ROL 的 SETTLE/verify 子程序；
- PGL/OPT → 终局放置的目标位姿与迁移统计。

这样不需要重写动作模型，只是给它加一个“执行层”。

## 5. 数据引擎：轴随机失败与反事实恢复

### 5.1 ARD：五轴失败合成

| 轴 | 合成方法 | 控制变量 | 标签 |
|---|---|---|---|
| 位置 | 对目标/容器/放置区做刚体平移/旋转；从演示分布内采样 + 10–20% 外推 | 平移量、旋转角、是否超出工作空间 | F2；新目标位姿 |
| 干扰物 | 在目标附近/接近路径插入 1–5 个杂物；保证不完全遮挡 | 数量、尺寸、位置、颜色 | F1/F4；碰撞/遮挡标签 |
| 背景 | 替换桌布颜色/纹理/光照；用分割 + 2.5D 编辑保持接触阴影 | 颜色、纹理、光照方向 | 视觉不变性正样本 |
| 未见物品 | 用类别内不同颜色/形状/材质的资产替换目标；保持 affordance | 类别、尺寸、材质 | F1/F3；类别级关键点 |
| 人为干扰 | 官方 human 备注回放（1-DOF 平移、完成后撤销、移走目标） | 时机、方向、幅度 | F2/F6；回归事件 |
| 执行失败 | 夹爪位姿噪声、时序抖动、滑落/掉落、碰撞 | 噪声幅度、时机 | F3/F4/F5/F7 |

**原则**：

- 不追求全物理高保真；只要求“失败状态”和“算子结果”可用于训练 FMR/BRS。
- 每个合成样本保留“来源演示 + 编辑参数 + 失败模式标签”，便于审计和消融。
- 背景/干扰物编辑不能改变任务语义（目标仍可见、容器仍在）；否则标签会错。
- 未见物品替换要保证可抓/可放；否则不是“泛化”，是“不可解”。

### 5.2 CRO：反事实恢复结果

对每个失败状态 `s`，枚举候选算子 `a`，记录：

```text
(s, a) → (success, time, next_stage, step_score_delta, collateral_damage)
```

- 仿真/回放：用轻量孪生或 2.5D 回放，批量跑；目标 8 个高价值任务 ×5 轴 ×20 失败 ×8 算子 ≈ 6,400 条。
- 真机：调试槽选 2–3 个任务（T27/T10/T24），每任务 10–20 个失败状态 ×3 算子，校准时间/成功率。
- 数据增强：对同一 `(s,a)` 做多次随机种子，估计 `p_a` 的方差；BRS 用保守分位数（例如 25th percentile）而不是均值。

### 5.3 恢复演示采集

- **FLARE 式 bridging（[S19]）**：在演示段之间注入扰动，再补一段“从扰动回到原轨迹”的桥接；教策略从偏移状态继续。
- **CARE 式失败修正（[S21]）**：跑 base policy 收集失败，人工/脚本修正，形成恢复演示。
- **Backtrack 式回退（[S23]）**：不需要演示，直接反向回放 EE 轨迹；作为零数据基线。
- **官方 human 备注**：按剧本合成“破坏→恢复”对；训练 RSB 的 1→0 和 FMR 的 F6。
- **自然恢复片段**：从 33k 成功演示里挖“重抓/回退/重试”片段，弱监督。

### 5.4 数据规模与配比

| 数据 | 规模 | 用途 |
|---|---:|---|
| 官方 33,276 条 | 100% | 动作克隆/主干、SIR 预训练 |
| 轴扰动失败 | 8 任务 ×5 轴 ×20 = 800 状态 | FMR/SIR |
| 反事实算子 rollout | 800 ×8 = 6,400 | BRS 值头 |
| 官方 human 剧本 | 32 任务 ×2 ×50 = 3,200 | RSB/FMR |
| 恢复演示 | 2,000–5,000 段 | 动作专家/算子 |
| 真机校准 | 2–3 任务 ×10–20 状态 | 时间/成功率校准 |

训练配比建议：官方真实 ≥60%，合成/恢复 ≤40%；每批 50/50  nominal/recovery，避免遗忘。

## 7. 评测协议：先证明恢复比“不干预/简单回退”好

### 7.1 三级评测

1. **离线（每天）**：
   - 阶段谓词 F1、失败模式 macro-F1、BRS 校准（ECE/Brier）；
   - 反事实算子排序相关性（Spearman）；
   - 恢复率 = 成功恢复 / 恢复机会；
   - 净增益 = 恢复成功率 − 同状态 no-intervention/简单 backtrack 的成功率。
2. **本地（每周）**：
   - 回放/轻量孪生上的配对 A/B：同一失败状态，开/关 TRIAGE；
   - 误干预率：在“本来会成功”的 episode 上触发干预的比例；
   - 时间开销分布。
3. **平台（版本门）**：
   - 不计分单任务调试槽：T27（放置+撤销）、T10（插入+拔出）、T24（移动目标）、T19（闭合+拉开）中选 2–3 个；
   - 每个大版本最多 1 槽；判定：净增益 ≥5pp、误干预 ≤5%、无回归才进计分跑；
   - 正式计分跑 2 次（中期/终期）。

### 7.2 指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 任务成功率 | 官方 | 主指标，+8–10pp |
| 步骤分 | 官方 | 不下降；同分裁决 |
| 恢复率 | 成功恢复 / 恢复机会 | >40% |
| 干预 precision | 有效干预 / 干预 | >60% |
| 误干预率 | 本会成功却被干预 / 本会成功 | ≤5%（reset ≤2–3%） |
| 净增益 | 恢复 − placebo | ≥5pp |
| 时间开销 | 恢复额外耗时 | 中位 <15s，p95 <45s |
| 校准 | ECE/Brier | ECE <0.05 |

### 7.3 对照与消融

- **Placebo**：同一失败状态，不干预/普通重跑；用于扣除 base policy 自身的随机性（参考 [S26]）。
- **简单回退**：固定时间触发 + 反向回放（Backtrack），作为强基线。
- **固定规则**：FMR 规则 + 固定重试次数，无 BRS。
- **完整 TRIAGE**：SIR+RSB+FMR+ROL+BRS。
- 消融：SIR on/off；RSB 单调 vs 可逆；FMR vs 通用 retry；BRS vs 固定规则；算子逐个去掉；预算/阈值扫描；单 checkpoint vs 外部 VLM（只做离线对比，不进正式提交）。

### 7.4 实验矩阵

| ID | 配置 | 验证 |
|---|---|---|
| E0 | WLA/GPR 基线 | 复现 |
| E1 | +SSG+RSB（规则） | 步骤状态/撤销检测 |
| E2 | E1+SIR | 关系/位姿/失败 F1 |
| E3 | E2+FMR | 失败模式路由 |
| E4 | E3+ROL（固定规则） | 算子有效性 |
| E5 | E4+BRS | 预算/阈值/净增益 |
| E6 | E5+ARD/CRO 全量 | 数据规模增益 |
| E7 | 蒸馏/量化 | 延迟/部署 |

### 7.5 失败判据（No-Go）

- 配对净增益 <5pp；
- 误干预率 >5%；
- 恢复时间中位 >20s 或 p95 >60s；
- FMR macro-F1 <0.5；
- SIR 相对位姿误差 >2cm/10°；
- 正式跑成功率低于基线（回归）。

任何一条触发，回退到最小版本（SSG+RSB+Backtrack+Settle），不把复杂调度器带进正式提交。

## 8. 创新点清单（持续迭代）

> 状态：押注=本轮主线；保留=沿用；升级=旧点改造；降级=保留但非主回路；砍=不做。

### I1 TRIAGE 执行层（新增，押注）
- **动机**：成功率优先、失败是常态、180s 预算；现有 VLA 没有“诊断→路由→调度”的执行层。
- **差异**：不是再加一个恢复策略，而是把恢复做成半马尔可夫调度；有“不干预”和“转步保步骤分”。
- **可行性**：所有学习头可挂在同一 checkpoint；算子多为脚本；接口支持。
- **资源**：8×H100 2–4 周；2–3 个调试槽。
- **步骤**：SSG→RSB→SIR→FMR→ROL→BRS→联合微调。
- **风险**：规则/单模型合规；误干预；统计噪声。
- **状态**：押注。

### I2 SIR 场景不变关系状态（新增，押注）
- **动机**：五轴本质是关系/外观/位置变化；像素端到端容易学 shortcut。
- **差异**：object-centric slots + 类别级关键点 + 关系图 + 时序记忆；训练用五轴对比不变性；推理只跑单 checkpoint。
- **可行性**：复用 VLA 视觉 token；辅助头 50–150M；数据可用官方 + 合成编辑。
- **资源**：8×H100 1–2 周；无需外部检测器常驻。
- **步骤**：槽/关键点→关系图→对比预训练→与动作头联合。
- **风险**：透明/布料/小件槽不稳；合成编辑域差。
- **状态**：押注。

### I3 RSB 可逆步骤信念（新增，押注）
- **动机**：官方 human 备注里大量“完成后撤销”；单调进度计数器会假完成。
- **差异**：HMM + 双阈值滞回 + 1→0 回归；步骤图含独立分支；不是简单状态机。
- **可行性**：谓词头小；标签可从演示 + 合成撤销得到。
- **资源**：无需新数据；CPU/小 GPU。
- **步骤**：解析 score_steps→谓词→HMM→回归检测→接 FMR/BRS。
- **风险**：谓词噪声导致误回退；用滞回 + 多帧确认。
- **状态**：押注。

### I4 FMR 失败模式路由（新增，押注）
- **动机**：不同失败需要不同恢复；通用 retry 会抓错/撞坏/浪费时间。
- **差异**：9 类失败 ×算子路由；训练用五轴扰动 + 官方备注 + 真实失败；推理是单头。
- **可行性**：分类头小；标签可合成；规则先验兜底。
- **资源**：8×H100 数天；真实失败标注 1–2 人周。
- **步骤**：失败注入→标注→训练→校准→路由表。
- **风险**：失败模式重叠；校准难；用 BRS 的“不干预”兜底。
- **状态**：押注。

### I5 BRS 预算化恢复调度（新增，押注）
- **动机**：180s 硬预算；不是所有失败都值得救；RESCUE（[S25]）证明误干预会破坏成功 episode。
- **差异**：半马尔可夫/最优停止；成功率先行、步骤分次之；时间影子价格；有“转步”动作。
- **可行性**：状态空间小（≤5 步 ×9 模式 ×时间 bin）；值头小；规则版可先上线。
- **资源**：CRO 6,400 条；8×H100 数天。
- **步骤**：形式化→值头→阈值校准→调试槽 A/B。
- **风险**：值估计偏差；时间成本标定；统计噪声。
- **状态**：押注。

### I6 ROL 恢复算子库（新增，保留）
- **动机**：把恢复拆成可复用的宏动作，而不是每任务写死。
- **差异**：12 个动作（含 CONTINUE）；前置/时间/风险表；单模型条件推理 + 脚本。
- **可行性**：大部分是 waypoint/夹爪/慢速释放；RESET 只对刚体。
- **资源**：工程 2–3 人周；真机校准。
- **步骤**：算子实现→单元测试→离线 rollout→真机。
- **风险**：RESET 在布料/透明上失效；用分桶回退。
- **状态**：保留。

### I7 ARD 轴随机失败数据（升级 NRB/ACP）
- **动机**：官方数据全是成功演示；失败数据是恢复训练的前提。
- **差异**：五轴对齐 + 官方 human 剧本 + 执行扰动；不是随机噪声。
- **可行性**：2.5D 编辑 + 回放；不需要全物理孪生。
- **资源**：8×H100 数天；资产许可逐个核。
- **步骤**：编辑器→轴脚本→失败注入→QA→入库。
- **风险**：合成域差/负迁移；真实混采 + GF 软权重。
- **状态**：升级。

### I8 SSG 步骤图（升级为 RSB 的结构）
- **动机**：官方公开 32×步骤/权重；给恢复提供阶段/依赖/分值。
- **差异**：增加依赖边、独立分支、可逆谓词；不再只是线性状态机。
- **可行性**：解析 JSON + 规则；CPU。
- **资源**：1 人周。
- **步骤**：解析→图→谓词→独立性标注→接 RSB。
- **风险**：官方步骤文本与真实谓词有语义差；用演示统计校准。
- **状态**：保留/升级。

### I9 PGL/OPT/SVL 放置模块（保留）
- **动机**：终局放置仍是成功闸门；第 7 轮的证据不变。
- **差异**：从“主押注”降为“TRIAGE 的终局子模块”；SVL 变成 ROL 的 SETTLE。
- **可行性**：第 7 轮已设计。
- **资源**：沿用。
- **风险**：透明/小件位姿估计；分桶回退。
- **状态**：保留。

### I10 ICR 检索上下文（降级）
- **动机**：33k 是现成少样本库；检索可提供动作先验。
- **差异**：原为第 7 轮主押注；本轮降为 PGL/OPT 可选上下文。
- **可行性**：缓存/ANN 可行，但延迟/复杂度高。
- **资源**：8×H100 1–2 天建库；延迟压测。
- **风险**：p99 超标；透明任务键失效。
- **状态**：降级（非主线）。

### I11 L2L 产学研数据协议（降级）
- **动机**：背景/位置轴多样性；实验室网络是便宜来源。
- **差异**：从“主数据农场”降为“合规确认后的补充”。
- **可行性**：高校 G1 保有量已被公开证实；但规则未明确外部数据。
- **资源**：3 实验室 ×2 任务 ×100–200 条。
- **风险**：规则不允许；默认 OFF。
- **状态**：降级。

### I12 DebugLoop 平台调试回路（保留）
- **动机**：真机反馈比自建孪生可信；发布门。
- **差异**：每大版本 1 槽；任务选择 T27/T10/T24/T19；判定净增益/误干预。
- **可行性**：profile 页已提供。
- **资源**：预约/管理。
- **风险**：槽位稀缺；规则变化。
- **状态**：保留。

### I13 GPR-VLA / WLA 主干（保留）
- **动机**：唯一学习主干；动作专家 + 目标残差 + 可逆信念。
- **差异**：本轮加 SIR/RSB/FMR/BRS 头；动作路径不变。
- **可行性**：Apache-2.0；24GB 可微调。
- **资源**：沿用。
- **风险**：底座能力上限；LoRA 分级。
- **状态**：保留。

### I14 Placebo/Net-gain 评测协议（新增，重要）
- **动机**：恢复文献里很多“增益”是 base policy 自身随机性；RESCUE（[S25]）与 [S26] 证明必须做 placebo。
- **差异**：同一失败状态、同一初始条件，A/B/no-intervention 三臂；配对统计。
- **可行性**：离线回放 + 调试槽。
- **资源**：低。
- **步骤**：定义配对集→三臂→bootstrap→发布门。
- **风险**：真机无法完全配对；用同任务/同初始条件近似。
- **状态**：押注（方法学）。

### 已砍/降级清单
- 全 32 任务高保真孪生；自由仿真数据；运行时仿真/MPC；仿真 RL；布料/拉链/透明全物理；WMA-0 进主路径；每任务 LoRA/模型合并；多模型 agent 拼装；ICR 作为主线；L2L 作为主线。

## 9. 风险、合规与开关

| 风险 | 概率 | 影响 | 缓解 | 停止条件 |
|---|---|---|---|---|
| 单模型规则不允许“多 head + 算子库” | 低 | 高 | 所有学习组件同一 checkpoint；算子确定性代码；模型卡披露 | 官方明确禁止 → 去掉学习头，只保留规则版 |
| 外部数据/教师模型不允许 | 中 | 高 | 默认只用官方数据 + 官方 WLA；教师仅离线蒸馏并确认 | 明确禁止 → 不做蒸馏 |
| 恢复误干预破坏成功 episode | 高 | 高 | “不干预”默认；δ 阈值；误干预 ≤5%；reset ≤2–3% | 误干预 >5% → 关闭 reset/redo |
| 失败检测/路由不准 | 高 | 中 | 规则先验 + 校准 + BRS 保守分位数 | macro-F1 <0.5 → 回退通用 retry |
| 恢复时间超预算 | 中 | 高 | 时间影子价格；每算子 timeout；剩余时间预留 | 中位 >20s → 限算子 |
| 合成失败域差/负迁移 | 高 | 中 | 真实混采 ≥60%；GF 软权重；QA | 合成增益 <0 → 只用真实 |
| 透明/布料/小件 SIR 失效 | 高 | 中 | 分桶回退到 RSB+Backtrack；不做位姿迁移 | 该桶恢复率 <基线 → 关 SIR |
| 统计噪声 | 高 | 中 | 320 trials + 配对调试槽 + bootstrap；目标 +8–10pp | CI 跨 0 → 不上线 |
| 调试槽稀缺/规则变化 | 中 | 中 | 每版本 1 槽；离线兜底 | 无法验证 → 保守提交 |
| N 端口/延迟 | 中 | 高 | FLEET 工程检查单；p99 压测；状态隔离 | p99 >100ms → 降 K/量化 |

合规开关：

```yaml
policy:
  single_checkpoint: true          # 所有学习组件同一权重
  external_models_at_inference: false
  external_data: false             # 默认 OFF；邮件确认后开
  teacher_distillation: false      # 训练期；需确认
  anchor_overlay: true
  settle_verify: true
  reset_object: true               # 仅刚体/已建模
  bank_advance: true               # 仅在 episode 未终止时
  debug_loop_budget_per_release: 1
  max_recovery_time_short: 60      # 秒
  max_recovery_time_long: 90
```

## 12. 开放问题

1. 评测器在“失败”时是否立即终止 episode？如果立即终止，BANK_ADVANCE（转步保步骤分）就没有执行窗口；如果不终止，它可以在成功无望时刷步骤分。
2. 单模型边界：同一 checkpoint 的多个头 + 确定性算子库是否算“同一模型”？外部教师模型仅离线蒸馏是否允许？需要邮件确认。
3. N 台评测机器人的准确数量、端口并发/延迟上限；是否允许同一模型多进程/多副本。
4. human 备注编号（human_1/human_4/unseen_object_3）是轴编号还是试次编号？评测是否按这些剧本采样？
5. 不计分单任务调试的可用次数/成本/是否随机化泛化条件。
6. 步骤分的聚合公式（按 episode 部分分平均？取最好？）；成功率与步骤分是否真的只在同分时使用。
7. 语言指令是英文 5 复述之一、中文，还是未见复述？SSG 匹配的兜底强度。
8. 外部数据（自采/实验室）是否允许？预训练权重（含论文方法）是否允许？
9. 评测中允许的连续重试/自我中断上限（180s 之内）是否有隐藏规则。
10. 真实榜单发布后，重跑“失败 mass / 恢复杠杆”假设；用真实分轴数据校准 BRS。

## 13. 一句话押注

**把恢复做成执行层的调度问题：用 SIR 把五轴场景压成不变的关系状态，用 RSB 处理“做完又被撤销”，用 FMR 把失败路由到 12 个动作（含 CONTINUE），用 BRS 在 180 秒内按“成功率先行、步骤分次之”的字典序决定救/不救/换步；这是 UniBot 当前最值得押注的创新点。**
