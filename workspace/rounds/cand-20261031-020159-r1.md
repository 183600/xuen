# 第 13 轮 · INTENT-TWIN：把 CHUNK-SERVO 的几何闭环升级为「相位意图重锚定 + 交互孪生反事实重绑定」

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。用户称本轮为灵感循环第 1 轮，但状态文件已延续到第 12 轮；为保持编号连续，本轮记为第 13 轮。三个灵感词是「意图识别」「数字孪生」「个性化交互」。本轮不推倒第 12 轮 CHUNK-SERVO，而是把它从「几何闭环」升级为「语义意图 + 交互孪生 + 几何伺服」三层闭环：**VLA 仍然只做一个模型；新增的意图图、相位路由、交互孪生、反事实渲染和每机器人标定全部是确定性/符号/几何模块，不引入第二个学习模型。**

## 0. 先给结论：榜首不到 30%，缺的是三个闭环，不是更大的模型

截至 2026-10-31，官网榜单 JSON 仍是 8 个模型：**MolmoAct2 29.7%、WALL-OSS-0.5 28.5%、DreamZero 27.9%、Spirit-v1.5 25.9%、DM0 23.5%、π0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%**。头尾只差 9.2pp；榜单 JSON 的 `generated_from` 仍是 `gen_leaderboard.py`，步骤分与成功率回归 **R² > 0.999999**、斜率约 **1.3**，任务成功率不是 10% 的整数倍，详情视频仍是占位。这说明榜单仍是**脚本生成的预览/合成数据**，不能当作 SOTA、任务难度表或失败分布；但“所有模型都卡在 30% 以下”这个量级与官方规则、数据形态是相容的，可以作为弱先验。

我的判断是：共享瓶颈不只在最后 3 厘米的几何接触，还在三个更靠上的闭环：

1. **语义意图闭环**：VLA 一次输出 30 步 chunk，chunk 内不看世界；多阶段任务（整理文具、装袋、叠毛巾、拼单词、装箱）在阶段切换时容易“继续执行旧意图”。HINT 在 WALL-OSS-0.5/π0.5 上、在水果分拣/拼单词/轴孔装配这类与 UniBot 高度重叠的任务上，用相位触发的 VLM 重锚定把平均 Full SR 提高 **+18.6pp / +41.4pp**，且不增加可训练参数。这是“意图识别”最直接的证据。
2. **交互闭环**：20% 的 trial 有人为干扰，规则原文是“临时改变物品位置等”——这是**物体位移**，不是社交/偏好交互。当前策略通常把“目标突然移动”当成异常：要么停住，要么按旧目标抓空。DPP 的思路是对移动目标预测未来交互位置、构造反事实观测，让同一个 VLA 在新位置上重新规划，且不需要在动态数据上额外训练。
3. **具身闭环**：评测跨 N 台机器人，相机内参/外参、TCP、桌面高度、网络 RTT 都可能不同；同一套固定增益在 A 机器人上稳、在 B 机器人上振荡。这里的“个性化交互”不是用户偏好，而是**每台机器人/每个 episode 的几何、延迟、检索个性化**。LIBERO-PeRM 说明真正的“个性化操作”零样本仍很难、需要 SFT；我们没有偏好数据，也不应该把宝贵的 320 trials 押在不可评分的社交个性化上。

所以本轮的押注是 **INTENT-TWIN**：

> 用同一个 WLA checkpoint 的 VLM 在 episode 开始时生成「意图图」（子任务、目标物、目标位置、完成检查），在相位切换/人为干扰时做稀疏重锚定；用交互孪生跟踪物体、推断人的新目标、把“物体将被移到哪里”渲染成反事实观测再喂回 VLA；用 CHUNK-SERVO 的 5 步视觉伺服负责最后 3 厘米；用每机器人/每 episode 的标定把几何和延迟对齐。**不训练第二个模型，不做完整场景重建，不做社交/偏好个性化。**

一句话：**把“预测 1 秒的动作”升级为“维护一张可被世界打断的意图图，并在世界被打断时让同一个 VLA 看到反事实的未来”。**

2026-10-31 逐数据集复核 `meta/info.json`，HangCup、ArrangePlates、StoreCups、StorePaddle、PourOutMedicine、PlugInEthernet 等均包含：

即腕部 RGB 有 **color 内参 + 畸变系数**；头双目仍有完整标定（基线 **58.2526mm**，`fx≈282`）。仍缺的是**腕部到 EE 的外参**。这改变了 CHUNK-SERVO 的可行性判断：

- 可以做腕部 IBVS（图像空间）和部分 PBVS（用头部双目/桌面平面补 3D），不再被“腕部无内参”卡死。
- 不能假设腕部外参已知；需要每机器人用夹爪几何做一次 PnP，或只用腕部做 2D 伺服、用头部做 3D 目标。
- 第 12 轮把“腕部内参”列为 blocker 的段落必须在本轮修正；否则会误导后续实验排序。

### 1.3 `action.pivot` 的 7 维语义：数据集 README 给了，API 仍需实测

数据集 README（2026-10-31 复核）明确 `action.pivot` 的 7 维是：


`base_command` 是 4 维（`vx, vy, angle_z, height`）；`gripper_controls` 是 4 维（`left_trigger, left_squeeze, right_trigger, right_squeeze`）。挑战赛 API 的 `action.pivot` 也是 7 维，很可能同源，但**不能假设顺序完全一致**：必须用 `example/example_env.py` 和单任务不计分通道做一次逐维小动作验证。若无法验证，默认把 `pivot[3:6]` 置零，只用双臂 + 夹爪 + 底盘平移，避免把腰部/头部位移当成动作维度。

### 1.4 人为干扰是“物体位移”，不是社交互动

规则中英文两版都写的是“临时改变物品位置等”（temporarily change object positions, etc.）。这意味着：

- “意图识别”在干扰场景下的核心不是读人的情绪/偏好，而是**推断人把哪个物体移到了哪里、人的目标位置是什么、机器人当前子任务是否还有效**。
- “个性化交互”不能解释成“记住这个人的偏好/风格”；评测是独立 reset 的 10 次运行，跨 trial 记忆还有公平性/隔离风险。我们只做**每机器人/每 episode 的几何与延迟个性化**，以及**当前 episode 内对人的运动意图的个性化推断**。
- 不要假设人能提供语言/手势/触觉反馈；API 只有四路 RGB + 本体状态，没有音频、没有力/触觉、没有人类骨架。

### 1.6 官方模型：ER-1/ER-Flow 的输出正好是意图锚定与干扰检测的原语

- **UnifoLM-ER-1 4B**（Qwen3-VL-4B）：点预测、物体检测、多图推理、2D 轨迹预测、3D 物体检测、多图空间 QA。它可以在同一模型内回答“目标在哪、下一接触点在哪、两视角是否同一物体”。
- **UnifoLM-ER-Flow**：在 ER-1 上增加 interaction-centric world modeling、未来动态区域预测、光流预测。它天然适合“人正在移动物体”的区域检测。
- **UnifoLM-WLA-1.0 6B**：基于 ER-1/ER-Flow + MMDiT action expert；2500h、64 任务；`chunk_size=30`、`target_fps=30`、4 步去噪；冻结 VLM、只训 action head + projector；24GB 可微调。

**关键工程判断**：PTIA/HIB 的 VLM 查询必须尽量走**同一个 WLA checkpoint 内部的 VLM/ER-Flow**；如果官方 server 不暴露查询接口，可以给同一进程加一个 `query_vlm` 方法，而不是再加载一个 ER-1。若做不到，就退化为确定性光流/模板匹配，不加载第二个学习模型。这是单模型合规的底线。

### 1.7 近期证据：HINT/DPP 最贴题，FaultEval/Recova/Kintsugi 可作恢复层

- **HINT**（arXiv 2609.02653，2026-10-31 复核）：相位触发的语义推理 + 多视角 grounding + 视觉跟踪 + 图像空间高亮/attention-prior 注入；不增加可训练参数；在 WALL-OSS-0.5 上平均 **+32.9 IS / +29.0 Sub SR / +18.6 Full SR**，在 π0.5 上 **+50.2 / +41.1 / +41.4**（六个 task-setting 对的平均）。任务包括水果分拣、拼单词、轴孔装配，和 UniBot 的 Fruit Sorting / Spell Robot / Plug In Ethernet 高度重叠。这是 PTIA 的最强外部证据。
- **DPP**（arXiv 2609.33172，2026-10-31 复核）：Dynamic Predictive Planning with World-Action Models；对移动目标预测未来交互位置，构造反事实观测，不需要在动态数据上额外训练；单张消费级 GPU。和 HIB 的“人移动物体”场景同构。
- **FaultEval**（ICML 2026, PMLR 306）：VLM-VLA 协作做故障诊断与回滚；LIBERO 上界 +13%，真实机器人 +35%。可做 PTIA/HIB 失败后的诊断层，但不要把它做成第二个策略。
- **Harness VLA**（arXiv 2607.08448）：冻结 VLA + 解析原语 + 记忆引导 agent；LIBERO-Pro +38.6pp、RoboCasa365 +25.4pp。它证明“符号 harness”有效，但外部 LLM agent 有单模型合规风险；我们只借“harness”思想，不借外部 LLM。
- **Recova**（arXiv 2610.01178）：在数字孪生中发现恢复技能，再迁移到真实机器人。**Kintsugi-VLA**（arXiv 2609.31048）：把失败 rollout 变成恢复数据，仿真里 +5.8–6.7pp 恢复率。两者支持“用孪生合成恢复数据”，但都需要额外训练/仿真，本轮只作为 P2 观察项。
- **Splat2Act**（arXiv 2610.13945）：手机扫描得到 photorealistic digital twin，生成演示再微调 VLA；真实抓取 63.9%。太重，且评测场景未知，本轮剪枝。
- **LIBERO-PeRM**（arXiv 2610.22372）：个性化操作基准；当前 VLA 零样本个性化仍难，SFT 后偏好可学。它反证了“社交/偏好个性化”在没有数据时不可行；我们只做几何/延迟个性化。
- **SocialVLA**（arXiv 2610.02360）：靠音频/人类反应检测失败；UniBot 没有音频，且人是干扰者不是合作者，不适用。

### 1.8 统计功效：human 轴单独看不够，优先做全 trial 机制

32 任务 ×10 次 = 320 trials。若基线成功率约 25%，单 trial 方差 p(1-p)≈0.1875，320 trials 的 **SE≈2.42pp**；人为干扰轴只有 32×2=64 trials，**SE≈5.4pp**。也就是说：

- 全 trial +10pp 约 4.1 SE，值得做。
- human 轴 +10pp 只有约 1.85 SE，单独看不够显著；必须靠配对设计、bootstrap、以及“同一机制在非干扰 trial 也不退化”来支撑。
- 因此本轮优先级：**PTIA（全 trial 语义）> CHUNK-SERVO（全 trial 接触）> HIB（20% human）> PEP（全 trial 但增益较小）**。不要把所有工程都押在 human 轴上。

## 2. 诊断：四个闭环与对应模块

| 失败模式 | 典型任务 | 现有方案为什么不够 | 本轮模块 | 证据等级 |
|---|---|---|---|---|

| 最后 3 厘米接触失败 | Plug In Ethernet、Hang Cup、Unlock、Zip Up、Plug Charger、Arrange Test Tubes、Syringe Water Transfer | 开环 chunk 的 1 秒延迟；腕部外参未知；固定增益 | **CHUNK-SERVO 2.0** | A（第 12 轮接口事实）+ B（腕部内参已确认） |
| 跨机器人几何/延迟不一致 | 全部 32 任务 | 固定相机外参/TCP/增益；N 台机器人不同；RTT 抖动 | **PEP** | B（规则说 N 台）+ C（具体差异未知） |
| 多物体任务做漏/做重 | Color Arrangement、Fruit Sorting、Conveyor Sorting、Arrange Plates、Organize Bookshelf、Pick Out Batteries、Store Earphones | VLA 没有显式清单；步骤分按子任务给分，做漏会丢步骤分 | **意图图 + 完成检查** | B（评分步骤 94）+ C（步骤分细则未公开） |

四个闭环的关系不是并列，而是**语义图在上、交互孪生在中、几何伺服在下、具身标定在旁**：

```text
语言指令 ──> 意图图（VLM，同一 checkpoint）
                │  子任务/目标物/目标位置/完成检查
                ▼
          相位路由（夹爪事件/接触/停滞/光流/DTW）
                │  切换时重锚定
                ▼
          交互孪生（物体跟踪 + 人的目标推断 + 反事实渲染）
                │  反事实观测 / 目标更新
                ▼
          VLA 30 步规划（同一 WLA）
                │  30 步动作
                ▼
          CHUNK-SERVO 5 步执行（IBVS/PBVS + 演示检索）
                │
                ▼
          机器人 / 四路 RGB / 本体状态
                │
                └──> 回到相位路由与交互孪生
```

## 3. 方法：INTENT-TWIN

### 3.1 总览：三个新模块 + 一个保留模块

1. **PTIA（Phase-Triggered Intent Anchor，相位触发意图锚定）**：episode 开始时用 VLM 生成意图图；在阶段边界用同一 VLM 重新回答“当前子任务是什么、目标物在哪、下一目标在哪”，用几何跟踪维持两次查询之间的锚点，用图像高亮/语言提示把锚点注入 VLA。
2. **HIB（Human-Intervention Belief，人为干扰信念）**：用交互孪生跟踪物体与夹爪，计算“机器人动作解释不了的物体位移”残差；检测到人移动物体后，推断人的目标位置，预测未来交互时刻的物体位姿，构造反事实观测，让同一 VLA 在新位置上重规划。
3. **PEP（Per-Episode Personalization，每 episode 个性化）**：每机器人/每 episode 估计腕部内参使用方式、腕部到 EE 外参、TCP 偏移、桌面平面、动作偏置、RTT/延迟；用演示检索先验补目标；不改权重。
4. **CHUNK-SERVO 2.0（保留/升级）**：30 步 VLA 规划 + 5 步视觉伺服；目标来自演示检索的相对位姿/目标图；接触段法向缩幅；用腕部 color 内参做 IBVS，用头部双目/桌面平面做 3D。

### 3.2 PTIA：意图图 + 相位路由 + 锚点注入

#### 3.2.1 意图图（Intent Graph）

episode 开始时，用同一个 VLM 对语言指令 + 四路首帧做一次解析，输出一个**可验证的意图图**：

```json
{
  "task": "organize_stationery",
  "subtasks": [
    {"id": 1, "action": "pick", "target": "pen", "goal": "pencil_case", "check": "pen inside case"},
    {"id": 2, "action": "pick", "target": "ruler", "goal": "pencil_case", "check": "ruler inside case"},
    {"id": 3, "action": "close", "target": "pencil_case", "goal": "closed", "check": "case closed"}
  ],
  "constraints": ["do not move the cup", "keep the case on the table"],
  "confidence": 0.78
}
```

约束：

- 只允许使用首帧可见/指令明确提到的物体；不要凭空生成。
- 每个子任务必须有 `target` 和 `goal` 的 2D 点（head 图坐标）；3D 由双目/桌面平面恢复。
- 解析失败/低置信时，回退到**演示库里的任务模板**（按语言指令检索 top-1 模板），不要让 VLM 自由发挥。
- 意图图不是动作计划；动作仍由 VLA 生成。它只是“当前应该关注什么/什么算完成”的符号状态。

#### 3.2.2 相位路由（Phase Router）

相位切换不靠固定时间，而靠多信号投票：

```text
τ is a boundary if any 2 of:
  (a) gripper state flips (open<->close) and EE speed < v_eps
  (b) contact event: GEO-RESIDUAL / force proxy (EE velocity residual) > θ_c
  (c) plan progress stall: EE displacement < ε for K steps while plan says move
  (d) unexplained optical flow / object motion > θ_f
  (e) DTW alignment to a demo phase template crosses a boundary
```

触发后：

1. 若当前子任务的 `check` 已满足（VLM/几何验证），推进到下一子任务。
2. 若未满足且置信度高，重锚定当前子任务。
3. 若连续两次重锚定仍失败，进入故障诊断/回滚（FaultEval 式，但用同一 VLM，不加载第二个策略）。

#### 3.2.3 锚点注入（Anchor Injection）

VLM 返回目标 2D 点/框后：

- 用双目深度或桌面平面恢复 3D；用腕部内参做腕部视图的 2D 投影。
- 在 head 图/腕部图上画**细框 + 半透明高亮**（不要遮挡物体纹理）；HINT 的证据表明图像空间高亮比纯文本提示更有效。
- 若 VLA 暴露 cross-attention，可加 target-region bias；若不暴露，跳过，不强行改模型。
- 语言侧只加一句短提示（如“current target: pen in the case”），不把整张意图图塞进 prompt，避免 token 过长和指令冲突。

#### 3.2.4 查询预算

- 每个 episode 初始 1 次 + 每次相位切换最多 1 次 + 人为干扰最多 2 次；典型 4–8 次，远少于每步查询。
- 查询异步执行；未返回时用跟踪器维持上一锚点；不允许阻塞 `get_action`。
- 设最小间隔（如 0.5s）和置信度门；低置信不重锚，避免抖动。

### 3.3 HIB：交互孪生 + 反事实重绑定

#### 3.3.1 交互孪生状态

每 episode 维护一个轻量场景图：

```text
M_t = {T_e(t), T_j(t), v_j(t), c_j(t), T_h(t) if visible}
```

- `T_e`：EE 位姿（API 直接给）。
- `T_j`：目标/干扰物位姿；用 VLM 首帧点/框 + 双目/桌面平面初始化；之后用光流/模板/Kalman 跟踪。
- `v_j`：物体速度；由跟踪差分 + 低通。
- `c_j`：接触/抓取状态；由夹爪开合 + EE-物体距离 + 图像残差推断。
- `T_h`：人手/手臂；不做骨架，只做“运动区域”检测（ER-Flow 动态区域或光流阈值）。

#### 3.3.2 干扰残差

机器人动作能解释的物体运动：

```text
ΔT_j^exp = f(ΔT_e, a_t, c_j)
r_t = || ΔT_j^obs - ΔT_j^exp ||
```

- 若物体被夹住，`f` 让物体跟随 EE；若在桌面被推，`f` 用简单滑动模型；若自由，`f=0`。
- 当 `r_t > θ_r` 连续 K 帧，且物体不在夹爪中，判定为**外部干预**。
- 用动态区域/光流区分“人移动物体”与“机器人自己碰到但没夹住”；后者是接触失败，不是 human intervention。

#### 3.3.3 人的目标推断

不需要人的身份/偏好，只需要“物体将被放到哪”。两种估计：

1. **短时外推**：`T_j(t_int) = T_j(t) · exp(v_j · (t_int - t))`；`t_int` 是机器人按当前计划到达物体的时间。
2. **目标假设**：在场景图里枚举候选目标（桌面上的容器/凹槽/其他物体附近/桌外），用物体速度方向 + 人手位置 + 语言指令打分：

```text
g_h = argmax_g P(v_j, T_h, scene | g) · P(g | instruction)
```

若置信度低，不做“聪明”推断，直接等物体停稳后重锚定；不要追着运动中的物体跑。

#### 3.3.4 反事实观测

DPP 的关键不是“预测未来”，而是**把未来渲染给策略看**。我们做两种保真度：

- **2D copy-paste（默认）**：从当前 head 图裁剪目标 patch，按预测的 2D 位移粘贴到新位置；用深度比例缩放；旧位置用桌面纹理/简单 inpaint 填充；边缘 alpha 羽化。腕部视图若可见也做一份，否则只改 head。
- **3D 投影（可选）**：若已知物体 CAD/包围盒，投影到新位姿；否则用 2D。
- **保底**：若渲染置信度低，只在预测位置画一个高亮圈/箭头，不伪造纹理。

然后：

```text
a_{t:t+H} = π(· | o_t^cf, l, s_t)
```

同一个 VLA，不微调，不加载第二个模型。反事实观测只改变“物体在哪”，不改变机器人本体状态。

#### 3.3.5 决策策略

| 情况 | 动作 |
|---|---|
| 人还在移动物体，机器人离得远 | 等待/让行，保持安全距离；不要抢 |
| 物体被放到新位置后停稳 | 重锚定新位姿，继续当前子任务 |
| 物体被移到机器人不可达区域 | 若任务有替代物，改抓替代物；否则重规划/失败保护 |
| 被移动的是干扰物 | 忽略，继续原目标 |
| 人手进入机器人运动路径 | 停止/减速，等人手离开；安全优先 |
| 物体被拿走/遮挡 | 等一个短窗口；仍不可见则重锚定或失败保护 |

安全约束：人手/人臂进入安全距离时，EE 速度上限降低；不要为了 human 轴的分数冒碰撞风险。

### 3.4 CHUNK-SERVO 2.0：保留第 12 轮的几何闭环

- VLA 输出 30 步动作；每 5 步做一次视觉伺服；伺服目标是**演示检索的相对位姿/目标图**，不是绝对图像。
- 腕部有 color 内参后，IBVS 可以直接用腕部图像；3D 目标用头部双目 + 桌面平面，避免依赖未知的腕部外参。
- 接触段（插入/挂杯/拉拉链/拧瓶盖）法向缩幅、切向增益降低；检测到接触残差后切换到“小步 + 高增益阻尼”。
- `action_chunk_size=5` 作为默认；用 G5 扫 3/5/8/10，按 RTT 和任务阶段自适应。
- 第 12 轮的 `DG-KEYFRAME`、`GEO-RESIDUAL`、`FACT-VLA` 保留；本轮只改“目标从哪来”和“何时重锚定”。

### 3.5 PEP：每机器人/每 episode 个性化（不做偏好）

1. **腕部内参**：直接用 `meta/info.json` 的 color 内参；每台机器人可能有轻微差异，用夹爪指尖/已知标记做一次 PnP 校验。
2. **腕部到 EE 外参**：若官方未给，用腕部图像里可见的夹爪指尖（已知 URDF 3D 点）做 PnP；只做一次，不假设跨机器人相同。若 PnP 失败，退化到“腕部只做 2D IBVS，3D 用头部双目”。
3. **TCP 偏移**：从演示中估计“抓取时刻物体中心相对 EE”的偏移；按任务/物体聚类，运行时选 top-1。不是学习模型，是几何统计。
4. **桌面平面**：用双目点云 RANSAC 拟合；把 2D 目标投到平面，得到 3D 目标。
5. **动作偏置**：比较指令 EE 与观测 EE 的稳态差，估计 6D 偏置；低通更新，限幅。
6. **延迟/增益**：测 RTT 和动作执行延迟；按延迟选 chunk size 和伺服增益；每端口独立。
7. **演示检索先验**：按任务/阶段检索 top-k 关键帧，给伺服目标/相位模板；不更新权重。

“个性化”的边界：**只个性化几何、延迟、检索先验；不个性化偏好、情绪、社交风格；不做跨 trial 的人类身份记忆。**

### 3.6 单模型合规：一个 checkpoint，零新增学习权重

| 模块 | 是否学习模型 | 合规论证 |
|---|---|---|
| VLA 规划 | 是，唯一 | 官方 WLA checkpoint |
| VLM 意图解析/重锚定 | 同一个 checkpoint 的 VLM 分支 | 不加载第二个 ER-1；若 server 不暴露，则加查询方法或退化为确定性模块 |
| 交互孪生 | 否 | 几何/光流/Kalman/规则 |
| 反事实渲染 | 否 | OpenCV copy-paste/投影 |
| 相位路由 | 否 | 夹爪事件/接触/停滞/DTW |
| 演示检索 | 否 | 特征匹配/DTW，无学习权重 |
| PEP 标定 | 否 | PnP/RANSAC/低通 |
| 故障诊断 | 同一个 VLM | 不加载第二个策略；不微调 |

如果官方把“模型”解释得很宽（连 VLM 查询都算第二个模型），退化为 **C1 保守版**：不做 VLM 查询，只用光流/模板/DTW + CHUNK-SERVO；接受较小增益，但不冒违规风险。

### 3.7 运行时序（单次 `get_action`，目标 p99 ≤ 150ms）

```text
t0  evaluator 发观测（4 RGB + state + language）
t1  PEP：更新延迟/偏置/桌面平面（≤10ms）
t2  交互孪生：光流/跟踪/残差（≤30ms）
t3  相位路由：事件投票（≤5ms）
t4  若相位切换且 VLM 查询已缓存/已返回：更新意图图与锚点（≤5ms 注入）
t5  CHUNK-SERVO：若当前是执行块边界，算伺服修正（≤30ms）
t6  VLA：若需要新 30 步规划，异步取最新 plan；否则复用（≤50ms）
t7  动作序列化 + token（≤10ms）
```

VLM 查询不在关键路径上：异步发起，返回后写入下一块的锚点；如果没返回，用跟踪器维持。这样即使 VLM 200–500ms，也不会把 `get_action` 拖死。

## 4. 为什么可能涨点：四条推导

### 4.1 意图漂移上界

设一个 episode 有 `K` 个阶段，每个阶段边界的“意图切换”若未被策略观察到，旧计划在新阶段的有效性下降。把阶段边界看成一次“分布漂移”，PTIA 在边界重锚定相当于把 `K` 次漂移的误差重新归零。HINT 在 6 个 task-setting 对上平均 +18.6pp（WALL-OSS-0.5）说明这个上界在同类任务上不小。UniBot 的多阶段任务比例不低（Organize*/Pack*/Store*/Spell/Fold/Arrange），所以全 trial 期望增益主要来自这里。

### 4.2 干扰残差的可检测性

人移动物体时，物体位移不能被机器人动作解释；只要跟踪稳定，残差信噪比高。难点不是“检测到”，而是“检测到之后做什么”。DPP 的证据说明“预测未来位置 + 反事实观测”比“停住/按旧目标重试”更有效。UniBot 的人为干扰是物体位移，正好落在这个机制的作用域内。

### 4.3 反事实观测为什么可能有效

VLA 的训练数据是“成功演示的下一帧”；它没见过“目标被移走”的分布。直接把当前帧 + 语言“目标移动了”喂进去，模型可能仍按旧位置规划。反事实观测把“目标在新位置”变成**视觉上接近训练分布**的输入，模型更容易输出“伸向新位置”的动作。这是 DPP 的核心洞察，也是我们不训练第二个模型的原因。

### 4.4 统计功效与优先级

320 trials、p≈0.25 时 SE≈2.42pp；human 轴 64 trials、SE≈5.4pp。PTIA/CHUNK-SERVO 影响全部 trial，HIB 只影响 20%，PEP 影响全部但增益可能较小。因此：

- 先做 PTIA + CHUNK-SERVO 的离线/单任务 A/B；它们决定大盘。
- HIB 作为 human 轴的专项；用配对 bootstrap，不单独宣称 +10pp。
- PEP 是“防退化”的保险，不是主涨点；如果时间不够，保底做延迟/桌面平面/TCP。

## 6. 竞赛策略：320 trials 当投资组合

### 6.1 任务分层（按机制，不按时长）

| 层 | 任务 | 主投机制 | 理由 |
|---|---|---|---|
| **S 语义+接触** | Organize Stationery、Organize Pencil Case、Pack Bag、Store Racket、Spell Robot、Fold Towel、Toolbox Storage、Store Earphones、Pack Phone、Arrange Plates | PTIA + CHUNK-SERVO | 多阶段/多物体，阶段漂移和接触都可能 |
| **A 接触精** | Plug In Ethernet、Hang Cup、Unlock、Zip Up、Plug Charger、Arrange Test Tubes、Syringe Water Transfer、Stack Bowls、Paper Cup Stacking、Open Pill Bottle | CHUNK-SERVO + HIB | 最后 3 厘米/关节物体；人最容易移动目标 |
| **B 语义/感知** | Fruit Sorting、Color Arrangement、Conveyor Food Sorting、Fruit Basket Collection、Place Photo Frames、Organize Bookshelf、Pick Out Battery、Remove Pinned Note、Pack Doll | PTIA + 意图图 | 多物体分拣/放置；步骤分靠清单 |
| **C 长程但低接触** | Disconnect Ethernet、Stack Cups、Store Cups、Organize Tools、Arrange Plates | CHUNK-SERVO + 检索 | 时长不等于难度；先保稳 |

注意：这是**假设分层**，不是官方难度表；用单任务通道和离线数据修正。榜单预览只作弱先验。

### 6.2 单任务 A/B 组合

选 5 个任务做配对 A/B（同一 checkpoint、同一机器人、同一 reset 协议）：

1. **Plug In Ethernet**：接触精 + 人为干扰高价值。
2. **Hang Cup**：短任务、接触/挂取；检验 PTIA 是否对短任务无退化。
3. **Toolbox Storage**：最长任务、多物体；检验 PTIA/意图图。
4. **Spell Robot**：HINT 同任务证据；检验语义重锚定。
5. **Fold Towel**：可变形物体；防止“只在刚性物体上涨点”的假阳性。

通过标准：≥3/5 任务 +10pp；无任务退化 >5pp；p99 ≤150ms；HIB 误停 ≤5%。若 human 轴无法在单任务通道复现，不做 human 专项声明，只做离线/仿真 G9/G10。

### 6.3 优先级公式

```text
priority_t = (0.45 * q_t * Δ_servo + 0.35 * s_t * Δ_intent + 0.20 * Δ_human) / cost_t
```

- `q_t`：最近 3 厘米失败占比（离线/单任务估计）。
- `s_t`：阶段数/语义漂移风险（演示分割 + 任务语义）。
- `Δ_servo/Δ_intent/Δ_human`：预期增益（保守估计）。
- `cost_t`：工程/评测成本。

先做 `priority` 最高的 3 个任务；每轮用单任务通道更新 `q_t/Δ`；不要把 32 个任务各训一个策略（违规且过拟合）。

### 6.4 提交节奏

1. 先交**安全基线**：CHUNK-SERVO + 固定标定 + 保守停止；锁 tie-break（更早提交）。
2. 过 G8/G11 后交 **PTIA + PEP**。
3. 过 G9/G10 后交 **HIB**。
4. 每次提交保留回滚；记录单任务/全量 dry run 的 p99、误停、跨端口隔离。
5. 若 G12 单模型合规存疑，切 C1 保守版，不冒险。

| 剪枝项 | 原因 |
|---|---|

| 把腕部内参标定当 blocker | 已确认有 color 内参；外参另说 |

## 8. 风险与未知（按严重度）

1. **人为干扰协议未知**：何时介入、移动哪个物体、移动多远、是否可脚本化，官方没有完全公开；单任务通道是否支持 human 轴也未确认。缓解：设计通用残差检测 + 保守策略；向官方提问；仿真覆盖宽分布；不把 human 轴当唯一涨点。
2. **VLM 查询接口未知**：WLA server 是否暴露同一 checkpoint 的 VLM/ER-Flow 查询；若不暴露，PTIA/HIB 会退化。缓解：先做接口 spike；能加方法就加；不能就 C1。
3. **腕部到 EE 外参未知**：影响 PBVS/3D 抓取。缓解：夹爪 PnP；退化到头部双目 + 腕部 2D。
4. **反事实渲染保真度**：2D copy-paste 可能产生伪影，VLA 可能不买账。缓解：保守编辑/高亮保底；G10 先仿真后真机；与“只重锚定不渲染”做消融。
5. **VLM 延迟/幻觉**：4B VLM 在 24GB 上与 action expert 共享；查询可能 200–500ms；JSON 可能不合法。缓解：异步、缓存、模板回退、几何验证、查询预算。
6. **规则解释风险**：VLM 查询是否算“第二个模型”；跨 trial 记忆是否违规；外部工具是否允许。缓解：单 checkpoint、无权重更新、审计日志；必要时 C1。
7. **任务名映射错配**：HF 与榜单名称不一致，A/B 可能错配。缓解：建完整映射表；单任务通道用官方任务名。
8. **统计功效**：human 轴 64 trials，+10pp 只有 ~1.85 SE；不要过度宣称。缓解：配对设计、bootstrap、全 trial 机制优先。
9. **数据/算力**：33k episodes/169h；全量视频存储大；无 pandas/pyarrow。缓解：只取 state/action + 关键帧；流式读取；CPU 做检索。
10. **时间**：PTIA/HIB/PEP 三线并行会拖垮；缓解：PTIA 先做，HIB 次之，PEP 保底三项。

## 2. 问题形式化

把单次 episode 建模为带人类干预的 POMDP：

```text
M = (S, A, O, T, Z, R, γ)
s_t = (s_t^robot, {T_j(t)}, T_h(t), z_t)
o_t = (I_t^headL, I_t^headR, I_t^wristL, I_t^wristR, q_t, u_t, l)
a_t = (a_t^arm, a_t^grip, a_t^base, a_t^pivot)  # chunk
z_t = (k_t, g_t, b_t, checklist_t)               # 意图状态
```

- `z_t`：子任务索引、目标物、目标位姿、完成清单；分段常数，在相位边界/人为干扰时跳变。
- `T_h(t)`：人手/人臂运动区域（不做骨架/身份）。
- 人类干预：在随机时刻 `t_h` 改变某个物体位姿 `T_j`；机器人不知道 `t_h`，只能从观测推断。
- 目标：最大化成功率与步骤分；单模型；180s；N 端口独立。

**关键假设**（需验证）：

1. 同一 WLA checkpoint 可被查询 VLM/ER-Flow，或至少可加查询方法而不加载第二套权重。
2. 腕部 color 内参可用于 IBVS；腕部外参可通过夹爪 PnP 或退化方案解决。
3. 人为干扰至少包含“目标物被移动”，且移动后的位置在机器人可达/可观测范围内占多数。
4. 反事实 2D copy-paste 不严重破坏 VLA 的视觉分布。
5. 单任务通道能复现任务级成功率，可用于 A/B。

### 3.2 意图图 schema

```text
{
  "task_id": "organize_stationery",
  "language": "put the stationery into the pencil case",
  "subtasks": [
    {
      "id": 1,
      "action": "pick",
      "target": {"name": "pen", "point_head": [u, v], "point_wrist": [u, v], "bbox": [x1, y1, x2, y2]},
      "goal": {"name": "pencil_case", "point_head": [u, v], "bbox": [x1, y1, x2, y2]},
      "check": "pen inside pencil_case",
      "priority": 1
    }
  ],
  "constraints": ["do not move the cup", "keep the case on the table"],
  "source": "vlm|template",
  "confidence": 0.0
}
```

规则：

- 目标/目标点必须来自首帧可见区域或指令明确对象；否则 `source=template`。
- `check` 用可验证的视觉条件（包含/接触/关闭/堆叠高度），不写抽象语义。
- 解析失败 → 演示库模板 top-1；模板也失败 → 单子任务“完成指令”保底。
- 意图图可被 HIB 更新：只改当前/后续子任务的 `target/goal`，不重写已完成子任务。

### 3.3 相位路由信号

| 信号 | 计算 | 阈值/备注 |
|---|---|---|
| 夹爪翻转 | `grip_t != grip_{t-1}` 且 `||v_ee||<v_eps` | 最快、最可靠 |
| 接触残差 | `||v_ee^obs - v_ee^cmd|| > θ_c` 或 EE 位移停滞 | 需标定 |
| 计划停滞 | 计划要求移动但 EE 位移 <ε 连续 K 步 | K=5–10 |
| 未解释光流 | 物体区域光流 >θ_f 且机器人动作解释不了 | 与 HIB 共用 |
| DTW 相位 | 当前状态/动作序列对齐演示模板的相位边界 | 离线建库 |

投票：任意 2 个信号同时成立 → 边界；单信号 → 候选，下一帧确认。边界后最多 1 次 VLM 查询；查询未返回则用跟踪锚点继续。

### 3.4 交互孪生

状态：

```text
M_t = {T_e, {T_j, v_j, c_j}, T_h, table_plane, t}
```

- 初始化：VLM 首帧点/框 + 双目深度/桌面平面 → 3D；腕部视图用 color 内参投影。
- 跟踪：稀疏光流/模板 + Kalman；物体被遮挡时用最后速度短时外推，超过 0.5s 不更新则标记 `lost`。
- 接触：夹爪开合 + EE-物体距离 + 图像残差；`c_j∈{free, contacted, grasped}`。
- 人类区域：ER-Flow 动态区域或光流阈值 + 人手颜色/运动先验；不做身份/骨架。
- 残差：`r_t = ||ΔT_j^obs - f(ΔT_e, a_t, c_j)||`；连续 K 帧 >θ_r 且 `c_j!=grasped` → 外部干预。

### 3.5 反事实渲染

```text
input: I_head, mask_j, T_j(t), v_j, t_int, K_head, D_head
ΔX = T_j(t_int) · T_j(t)^{-1}
Δu = π(K_head, T_cam_base · (X_j + ΔX)) - π(K_head, T_cam_base · X_j)
patch = I_head[mask_j]
I_cf = paste(I_head, patch, shift=Δu, scale=D_j/(D_j+ΔZ))
I_cf = feather_blend(I_cf, inpaint(I_head, mask_j, table_texture))
```

- 默认只改 head 左图；head 右图按视差同步平移；腕部若可见也改，否则不改。
- 旧位置填充：桌面纹理/最近邻 inpaint；不做生成式修补。
- 保底：若 `mask_j` 面积 <阈值、遮挡、或 `Δu` 超出图像，改为在预测位置画高亮圈/箭头，不伪造纹理。
- 反事实观测只用于一次 VLA 查询；不进入训练数据；不跨 episode 缓存。

### 3.6 CHUNK-SERVO 2.0

- 规划：VLA 30 步；执行：5 步块；伺服：每块一次。
- 目标：演示检索的“受器→夹爪”相对位姿 + 目标图；按任务/阶段 top-k。
- 腕部：color 内参做 IBVS；3D 目标用 head 双目 + 桌面平面。
- 接触段：法向缩幅、切向增益降、阻尼增；检测到接触残差后切“小步高阻尼”。
- 增益/RTT：每端口测；`action_chunk_size∈{3,5,8,10}` 按延迟和阶段选。
- 安全：EE 速度上限、人手安全距离、力代理残差超限即停。

### 3.8 多端口与服务器

- 每端口一个 `PolicyService` 实例：独立 `reset()`、独立孪生/相位/缓存/统计；不共享 episode 状态。
- 共享：WLA 权重、VLM 查询队列、演示检索索引（只读）。
- VLM 队列按端口轮询 + 优先级（相位切换 > 人为干扰 > 初始解析）；单端口最多 1 个在途查询；超时丢弃。
- 端口 N：`8765..8765+N-1`；启动时健康检查；token 从 `metadata.token` 读，每次 `meta.token` 回传。
- 日志：每端口 p50/p95/p99、查询次数、误停、跨端口串扰检查。

### 4.1 `get_action`

```python
def get_action(obs, meta):
    check_token(meta)
    pep.update(obs)                          # delay/bias/table
    twin.update(obs)                         # track objects/human
    phase = router.update(obs, twin)         # event vote
    if phase.boundary:
        ig.maybe_refresh(obs, twin)          # async VLM, budgeted
    if twin.human_intervention():
        goal = twin.infer_human_goal(obs)
        obs_cf = cfr.render(obs, twin, goal) # copy-paste/projection
        plan = vla.plan(obs_cf, meta.language, twin.anchor)
    elif phase.boundary or plan is None:
        plan = vla.plan(obs, meta.language, ig.anchor)
    if servo.due():
        plan = servo.correct(plan, obs, twin, ig.anchor)
    chunk = plan.next_chunk(pep.chunk_size)
    return chunk, meta.token
```

### 4.3 相位路由

```python
def update(self, obs, twin):
    sig = {
        "grip": self.grip_flip(obs) and self.ee_slow(obs),
        "contact": self.contact_residual(obs) > self.theta_c,
        "stall": self.plan_stall(obs) > self.K,
        "flow": twin.unexplained_flow(obs) > self.theta_f,
        "dtw": self.dtw_boundary(obs) > self.theta_d,
    }
    votes = sum(sig.values())
    if votes >= 2:
        return Boundary(signals=sig)
    if votes == 1:
        self.candidate += 1
        if self.candidate >= 2:
            return Boundary(signals=sig)
    else:
        self.candidate = 0
    return NoBoundary()
```

### 4.4 HIB 检测与反事实

```python
def human_intervention(self, obs):
    for j in self.objects:
        if j.grasped:
            continue
        r = norm(j.delta_pose - self.expected_delta(j, obs))
        if r > self.theta_r:
            self.residual_count[j] += 1
        else:
            self.residual_count[j] = 0
        if self.residual_count[j] >= self.K:
            return j
    return None

def infer_human_goal(self, j, obs):
    if norm(j.v) > self.v_stop:
        return self.extrapolate(j, self.t_int)
    return self.best_goal_hypothesis(j, obs)
```

### 4.5 伺服

```python
def correct(self, plan, obs, twin, anchor):
    goal = demo_library.retrieve(anchor.task, anchor.phase)  # relative pose/image
    err = goal - twin.ee_relative(anchor.target)
    if twin.contact_state == "contact":
        err = normal_shrink(err) * self.gain_contact
    else:
        err = err * self.gain_free
    return apply_delta(plan, err, max_step=self.max_step)
```

### 5.2 数据与切分
