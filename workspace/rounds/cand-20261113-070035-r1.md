# 第 66 轮（新一轮灵感循环第 1 轮；承接第 65 轮「VISTA 故障可归因闭环」IP-214~223；本轮灵感：「失败恢复」×「用户体验」）

> 第 65 轮把「几何可证伪」升级为「故障可归因」，但它自述的最大风险仍悬在头顶：故障假设集有限、视觉与几何可能共因失效，FIR 会把未知复合故障强行塞进最近假设、只膨胀错误的球，而系统因为「已经归因」反而更自信地继续执行。更根本的缺口是：VISTA 的终点只有 `safe_idle` / `compliant retreat`——**它能安全地停下，却不能把任务救回来，也没有回答「用户愿不愿意、需不需要被打断」**。本轮的问题因此变成：
>
> **坏了之后怎样以最小用户代价恢复，并让恢复本身可验证、可理解、可信任。**

## 0. 直觉与动机

**灵感 1（失败恢复 → 恢复是对归因假设的第二次实验）**
直觉：第 65 轮把安全押在"归因正确"上，可归因本身可能是错的。与其在错误归因上"更自信地继续"，不如让恢复动作成为低成本的假设检验：在 H_geo / H_force / H_model / H_policy 下，同一个恢复动作（重试、重抓、重定位、零力窗重标定、换姿态）应当留下**可区分的成败签名**。恢复于是不只是补救，而是把"被动降级"变成"主动、可逆、还带任务收益的判别探针"——这直接攻击第 65 轮隐藏假设 A88：我们不要求第一次就归因正确，而要求**恢复结果能证伪它**。

**灵感 2（失败恢复 → 恢复比正常运行更危险，必须是二阶安全）**
直觉：正常执行被认证在安全集内；恢复却要主动离开安全集（重新接近、重新施力、移动到未验证区域）。所以恢复不能是安全证书之外的"例外通道"，而必须有自己的、更严的证书：**可逆性预算**（还能否回到已知安全态）、**不可逆动作预算**（最多允许几次不可撤销操作）、**恢复前缀截断**（一次只执行到下一个检查点）。恢复失败时也不能级联成"恢复的恢复"无限套娃，而要有深度上限与终止定理。

**灵感 3（用户体验 → 打断、等待、困惑、失信都是成本）**
直觉：一个"安全但每三步就停下问人"的系统，在真实用户眼里是失败的。UX 不是软指标，而是恢复决策的显式成本：打断成本、等待时间、解释复杂度、任务进度损失、信任校准误差、用户控制感。于是目标从"最大化任务成功率"改为"最大化**体验调整后的效用 EAU**"，并用"礼貌预算"限制单位任务内的打断次数。关键红线：**安全与知情同意是硬约束，体验只是安全可行集内的软目标；二者不可互换。**

**灵感 4（用户体验 → 可理解与可预期：不静默失败、不制造意外）**
直觉：用户对系统的信任不来自"从不出错"，而来自"出错时我能理解、能预期、能接管"。因此定义**失败可读性**（系统内部故障后验与用户理解到的故障之间的互信息 + 可操作性）与**意外度**（系统宣告的策略与实际执行策略的偏离）。UX 契约：任何不可逆动作、任何超出已宣告自主边界的恢复，都必须先宣告并在需要时取得同意；任何降级都不得静默发生。

**灵感 5（合流 → REVIVE：Recovery-Enabled Verified Interaction-aware Value-of-Escalation）**
闭环：VISTA 归因后验 → 恢复能力图谱 RCA（故障假设→候选恢复）→ 可逆性感知恢复证书 CRR（只执行认证前缀）→ 体验调整效用 EAU 与升级决策 EVA（自动恢复 / 询问 / 停止，含打断成本与同意边界）→ 恢复执行与恢复盾 SRA → 恢复失败则有限深度升级 → 恢复记忆 RML（带负迁移防护，只在语义流写）→ 可读解释 LEX 与信任校准 TCM → J_revive。**恢复既修复任务，又检验归因；用户体验既是被优化的目标，也是防止系统"静默挣扎 / 过度打扰"的约束。**

**灵感 6（组件原位升级）**
- **FIR → FIR-R**：恢复结果作为新证据回灌，后验在恢复后重估；支持"恢复证伪归因"。
- **CSC → CSC-R**：恢复动作的认证前缀 k*_rec，受可逆性预算与不可逆动作预算约束。
- **AFA → EVA**：探针目标从"降低故障熵"扩展为"在打断成本与恢复收益之间做价值权衡"。
- **CSP-V → RSP**：任务图增检查点 / 回滚锚点，恢复宏成为一等技能；检查点间距与恢复代价联立优化。
- **Shield → SRA**：恢复盾，硬约束 + 回退到最近检查点。
- **OLP/DIR → RML**：恢复案例库；检索到的案例必须重新认证（负迁移防护）。
- **AIC-V → AIC-R**：干扰集增"恢复诱发故障""用户误操作/缺席""恢复级联"。
- **J_vista → J_revive**：证书增 recovery_cert、reversibility_budget、eau、interruption_count、legibility、trust_calib、recovery_depth、announcement_hash。

## 1. 形式化定义（增量：定义 233–250）

- **定义 233（REVIVE 闭环）**：REVIVE = (VISTA, RCA, CRR, EAU/RUX, EVA, SRA, RML, RSP, LEX, TCM, J_revive)。不变式：恢复规划、恢复认证、EAU 计算、解释生成、信任更新、记忆写入只在语义流；实时流只执行恢复认证前缀、硬约束恢复盾、早停与宣告事件，零学习写操作。
- **定义 234（失败分类与可恢复性）**：失败事件 F=(F_safe 安全越界, F_attr 归因模糊, F_task 进度停滞/超时, F_user 用户推翻/缺席)。状态 s 对目标 g 是 (δ,B)-可恢复的，若存在恢复路线 r=(r_1,…,r_d)，使每个前缀获得 J_rec 认证、累计不可逆预算 ≤B、且到达检查点或目标概率 ≥1−δ。不可恢复时进入终止安全态并移交。
- **定义 235（恢复能力图谱 RCA）**：恢复原语库 R={retry, regrasp, re_approach, re_localize, recalibrate_null, compliant_retreat, ask_human, safe_stop, …}；每个原语携带前/后条件、可逆等级 rev∈{R0 可逆, R1 可回检查点, R2 不可逆}、时间/能量/注意力代价、所需传感器与证书模板。故障→恢复映射 Γ:H→2^R 给出候选集及先验成功率。
- **定义 236（可逆性感知恢复证书 CRR）**：恢复路线 r 的证书 J_rec=(prefix, b_irr, α_rec, ε_rev, checkpoint)。可逆性 ρ_rev(r) 为"在 m_rec 步内回到已知安全态的概率"；不可逆预算 b_irr(r)=Σ 1[rev=R2]·c_i。Valid(J_rec) ⇔ P(恢复前缀内伤害)≤α_rec ∧ b_irr≤B_irr ∧ (ρ_rev≥ρ_min ∨ 已取得用户同意)。执行只到 k*_rec，随后强制重评估。
- **定义 237（体验调整效用 EAU 与 RUX 指数）**：U(a)=w_g·E[ΔProgress] − w_s·E[Harm] − w_t·E[T_recovery] − w_i·N_int − w_c·C_cog − w_τ·|τ̂−τ*| + w_u·C_user；硬约束 Harm≤α_rec、不可逆动作需同意。RUX=[任务恢复率, 打断率, 恢复时延, 解释可懂度, 信任校准误差, 控制感] 的归一化向量；报告而不进入安全约束。
- **定义 238（升级价值分析 EVA 与同意边界）**：a*=argmax_{a∈{auto,ask,stop}} E[U(a)]，s.t. auto 仅当 J_rec 有效且 ρ_rev 足够。询问当且仅当 VOI=E[U(recover|人信息)]−E[U(recover)] 超过打断成本 c_int+c_delay 且 N_int<B_int；不可逆动作无论 VOI 多大都必须显式同意（同意边界）。
- **定义 239（可读解释 LEX 与宣告）**：解释 e 的目标是让用户正确识别故障类别并能选择下一步动作：L(e)=P(Ĥ_user=H|e)+P(正确下一步|e)，在长度/认知成本约束下最大化；解释模板=(发生了什么, 哪个证书/通道被触发, 将要做什么, 是否可逆, 用户可选项)。宣告 = 在执行前发布 (动作, 预计时长, 可逆等级, 升级选项)；意外度 S=D(π_announced‖π_executed)。
- **定义 240（信任校准 TCM）**：真实可靠度 τ*=P(成功|上下文, 已宣告保证)；用户信任 τ̂ 从接受/推翻/接管时延估计；校准误差 e_τ=|τ̂−τ*|。过度信任→增加解释与保守提示；信任不足→减少无效打断、展示可验证的自主边界。**禁止用降低安全来提升信任。**
- **定义 241（恢复记忆库 RML 与负迁移防护）**：案例 c=(上下文签名, 故障后验, 恢复路线, 结果, 证书版本)。检索需过上下文 OOD 门；负迁移风险 NT=P(结果不同 | 上下文距离>τ_ctx)。被检索案例只作先验候选，**必须重新走 CRR 认证**；只在语义流、且拿到结果与用户反馈后写入。
- **定义 242（恢复深度与终止）**：恢复尝试深度 d，边际收益递减 E[ΔU_{d+1}]≤γE[ΔU_d]（γ<1）。最优深度 D*=min{D_max, 首个边际收益<尝试成本的 d}；每层伤害预算按几何分配 α_rec,d=α_total·2^{−d}/2，保证 Σ_d α_rec,d≤α_total。全部失败→终止安全态 + 人工移交。
- **定义 243（恢复盾 SRA）**：实时恢复盾对每个恢复动作强制硬约束：力限、形变、速度、工作空间、人机距离、关节限位；任一越界立即中止并回退到最近检查点；只允许执行 J_rec 认证前缀 k*_rec。
- **定义 244（恢复感知技能规划 RSP）**：在 CSP-V 的块级任务图上增加检查点/回滚锚点；恢复宏作为一等边；规划目标为 EAU，硬约束为安全与同意；检查点间距 Δ 与恢复代价 c_rec 联立优化（过密→开销，过疏→回滚损失大）。
- **定义 245（UX 契约）**：三条硬规则——(i) **不静默失败**：任何 F 都必须产生带原因码与严重度的用户可见事件；(ii) **不制造意外**：S≤ε_surprise，非紧急中止须在 τ_announce 内宣告；(iii) **知情自主**：不可逆动作需同意，可逆动作可在已宣告自主边界内自动执行。优先级为：安全 > 同意 > 体验 > 任务进度。
- **定义 246（用户模型与权限分配）**：用户偏好向量 w=(w_g,w_t,w_i,w_c,w_u) 可从反馈更新，但 w_s 固定为硬约束、不可学习下调；系统/用户权限按 (风险, 不确定性, 可逆性) 动态分配，且权限提升须显式同意。
- **定义 247（REVIVE 证书 J_revive）**：J_revive=(J_vista, recovery_cert, rev_budget, eau_terms, escalation_decision, interruption_count, legibility, trust_calib, recovery_depth, announcement_hash, aic_r_ver)。Valid ⇔ Valid(J_vista) ∧ (auto⇒Valid(J_rec)) ∧ (不可逆⇒存在 consent_hash) ∧ 不可逆前已宣告 ∧ recovery_depth≤D_max ∧ 复用记忆已重新认证。
- **定义 248（REVIVE 闭环算子）**：语义流 [VISTA 归因→失败分类→RCA 候选→RSP 恢复锚点→CRR 认证→EAU/EVA 决策→LEX 解释/宣告→执行 k*_rec→结果回灌 FIR-R→RML 写入→TCM 更新→J_revive]；实时流 [残差采集→阶段判定→SRA 硬约束→恢复前缀派发→早停/回退→宣告事件]。
- **定义 249（共因与双重故障下的恢复）**：当故障后验仍模糊或恢复结果与所有假设都不符时，不强行归因也不无限恢复；判 `recovery_ambiguous`，执行"最小可逆回退 + 人工移交"，并把该案例标为未知故障写入 RML 的隔离区。
- **定义 250（失败后学习飞轮）**：用恢复结果与用户反馈更新 Γ、RCA 先验、RML 与检查点策略；更新前须通过 AIC-R 回归测试与分布漂移检测；所有更新只在语义流，实时流证书版本与记忆版本解耦，避免在线学习污染执行路径。

## 2. 关键算法骨架

```python
# EVA：自动恢复 / 询问 / 停止（语义流；安全与同意是硬约束）
def decide(post, s, pref):
    F = classify_failure(post, s)
    routes = rca.candidates(F, post)                 # Γ(H) + 先验
    certified = [r for r in routes if crr.valid(r, s)]  # 又恢复 + 可逆性 + 预算
    if certified:
        best = max(certified, key=lambda r: eau.auto(r, post, pref))
        if crr.irreversible(best) and not consent.granted(best):
            return ask_user(best, lex.explain(best))  # 不可逆：必须同意
        return auto(best)                            # 可逆：在自主边界内
    voi = eau.value_of_info(post, pref)
    if voi > pref.c_int + pref.c_delay and pref.n_int < pref.B_int:
        return ask_user(None, lex.explain_ambiguous(post))
    return stop_safely(post)                         # 终止安全态 + 移交

# 恢复执行（实时；只到认证前缀，越界回退检查点）
def execute_recovery(r, s):
    for i, a in enumerate(r.prefix[:r.k_rec]):
        announce_if_needed(a, r)
        if not sra.hard_constraints_ok(s, a):        # 力/形变/空间/人距/限位
            return rollback(s.checkpoint), 'recovery_aborted'
        dispatch(a)
        if sra.monitor_step(a).abort:
            return rollback(s.checkpoint), 'recovery_aborted'
    return observe_outcome(), 'recovery_done'

# 恢复结果回灌归因（FIR-R）：恢复既是修复也是检验
post2 = fir_r.update(post, outcome)
if max(post2.values()) < 1 - delta_fi and depth < D_max:
    depth += 1
    post = post2                                     # 有限深度，重新决策
else:
    finalize(J_revive, post2, depth)
```

## 3. 保证概要与推导要点（完整推导见产物区）

- **引理 9（恢复即检验）**：若对任意 H≠H′，恢复动作 r 的结果分布满足 KL(p(o|H,r)‖p(o|H′,r))≥κ_rec>0，则 d 次恢复尝试的期望对数似然比至少增长 d·κ_rec，后验熵下降；恢复在修复任务的同时降低归因不确定性。反之若 κ_rec≈0（恢复对故障不可分辨），恢复不应被当作归因证据。
- **引理 10（可逆性受限的恢复安全）**：若恢复路线满足 b_irr≤B_irr、每层伤害预算 α_rec,d 按几何分配、且 k*_rec≤m_rec，则恢复全过程累计伤害概率 ≤Σ_d α_rec,d≤α_total；当 b_irr=0 时可回检查点的概率 ≥1−ε_rev。故"恢复"不会把最坏伤害扩大到正常运行之外。
- **定理 9（REVIVE 端到端）**：在 A88–A98 下，Valid(J_revive) ⇒ (i) 失败要么被恢复、要么被升级/终止；(ii) 恢复伤害 ≤α_rec；(iii) 不可逆动作均有同意；(iv) 无静默失败且意外度有界；(v) 若恢复可分辨则归因改善，否则判 `recovery_ambiguous`；(vi) 打断次数 ≤礼貌预算。
- **定理 10（升级与停止的阈值最优性）**：在边际收益递减与 VOI 单调下，EAU 最优策略是阈值策略——可逆且认证通过则自动恢复；VOI>打断成本且未超预算则询问；否则停止；恢复深度按边际收益首次低于尝试成本处截断。证明用后向归纳与交换论证。
- **命题（UX 不削弱安全）**：因 w_s 为硬约束、同意为硬约束，改变 UX 权重只能在安全可行集内改变 auto/ask/stop 的选择，不能放行不安全动作。**若工程实现把它退化为标量加权和，则本命题失效**——这正是本轮风险的入口。
- **实时性**：恢复盾只增硬约束检查（<0.2ms）与宣告事件（<0.05ms），目标 ≤2.8ms；CRR/EAU/LEX/RML 全在语义流。

## 5. 本轮最大风险

**一句话**：把用户体验写进目标函数，等于在安全约束旁开了一个可交易的缺口——一旦打断成本、信任或"用户不想被打扰"被误估或被产品指标人为调低，系统就会用它来为跳过恢复认证、延迟升级、静默重试辩护，安全便从硬约束退化为效用项；而本轮"UX 不削弱安全"的命题恰恰只在 w_s 与同意是真正硬约束时才成立。

# 第 66 轮产物 · 创新点清单 v4：REVIVE（Recovery-Enabled Verified Interaction-aware Value-of-Escalation：失败可恢复 × 体验可度量 × 交互可解释的安全回环；RCA×CRR×EAU/RUX×EVA×SRA×RSP×RML×LEX×TCM×J_revive）

>
> 本轮不做第 5 个模态，也不推翻 VISTA，而是把"故障可归因"推进为"**故障可恢复、恢复可验证、交互可理解**"：用**恢复动作**作为低成本的第二次假设检验，用**可逆性预算**把恢复的二阶风险压回安全集，用**体验调整效用 EAU**与**升级价值分析 EVA**决定自动恢复/询问/停止，用**可读解释与信任校准**让用户理解并接管。核心命题：
>
> **恢复既是修复，也是实验；用户体验既是目标，也是硬安全集之外的软约束；安全与知情同意永远不可交易。**
>
> IP 编号：IP-224~IP-233（共 10 个），全部为第 65 轮组件之上挂载或原位升级。

## 2. 形式化定义（完整版）

**定义 233（REVIVE 闭环）** REVIVE 是 VISTA 的"可恢复 + 体验知情"升级：在 VISTA 的"语义流 ∘ 实时流"骨架上挂载 RCA（恢复能力图谱）、CRR（可逆性感知恢复证书）、EAU/RUX（体验调整效用）、EVA（升级价值分析）、SRA（恢复盾）、RSP（恢复感知技能规划）、RML（恢复记忆库）、LEX（可读解释）、TCM（信任校准），并原位升级 FIR→FIR-R、CSC→CSC-R、AFA→EVA、CSP-V→RSP、Shield→SRA、AIC-V→AIC-R、J_vista→J_revive。不变式：**恢复规划、恢复认证、EAU 计算、解释生成、信任更新与记忆写入只发生在语义流；实时路径只做恢复前缀派发、SRA 硬约束、早停/回退与宣告事件，零学习写操作。**

**定义 234（失败分类与可恢复性）** 失败事件集合 F={F_safe（安全通道越界）, F_attr（归因后验不集中）, F_task（进度停滞或超时）, F_user（用户推翻/停机/缺席）}。状态 s 对目标 g 是 (δ,B)-可恢复的，若存在恢复路线 r=(r_1,…,r_d) 满足：(i) 每个前缀均有 Valid(J_rec)；(ii) 累计不可逆预算 b_irr(r)≤B；(iii) 从 s 出发到达检查点或目标的概率 ≥1−δ。若不存在，则 s 不可恢复，进入终止安全态并请求人工移交。可恢复性不是布尔值：R(s)=sup_r P(reach checkpoint|r) 作为排序分数，但其上界必须由 CRR 认证而非经验估计。

**定义 235（恢复能力图谱 RCA）** 恢复原语库 R 中每个原语 r 携带：前条件 pre(r,s)、效果 eff(r,s)、可逆等级 rev(r)、代价向量 cost(r)=(时间, 能量, 用户注意力)、所需传感器与证书模板。故障→恢复映射 Γ(H)⊆R 给出每个故障假设下可尝试的恢复集合及先验成功率 p(o|H,r)。RCA 的价值不在"推荐一个动作"，而在**把恢复候选与故障假设显式绑定**：H_force→recalibrate_null（零力窗重标定）或 retry；H_geo→re_localize / re_approach；H_model→compliant_retreat / 换姿态；H_policy→重规划/缩小 H；F_user→ask_human / safe_stop。未知故障→最小可逆回退。

**定义 236（可逆性感知恢复证书 CRR）** 对恢复路线 r，证书 J_rec=(prefix, b_irr, α_rec, ε_rev, checkpoint)。可逆性 ρ_rev(r) 定义为"从任意恢复前缀状态出发，在 m_rec 步内回到已知安全态的概率"；不可逆预算 b_irr(r)=Σ_i 1[rev(r_i)=R2]·c_i。认证规则：
Valid(J_rec) ⇔ P(恢复前缀内某通道越界)≤α_rec
∧ b_irr(r)≤B_irr
∧ (ρ_rev(r)≥ρ_min ∨ 已取得 consent_hash)
∧ 每个 R2 动作前已宣告。
执行器只执行认证前缀 k*_rec，随后强制重评估；k*_rec≤m_rec，其中 m_rec 为恢复的不可逆视界（由恢复动作的停止距离与回滚锚点决定）。

**定义 237（体验调整效用 EAU 与 RUX）** 对决策 a∈{auto(r), ask, stop}：
U(a)=w_g·E[ΔProgress|a] − w_s·E[Harm|a] − w_t·E[T_recovery|a] − w_i·N_int(a) − w_c·C_cog(a) − w_τ·|τ̂−τ*| + w_u·C_user(a)。
硬约束：E[Harm|a]≤α_rec；任何 R2 动作需 consent_hash；N_int≤B_int。注意 w_s 在实现中不是有限大数，而是**字典序约束**：先可行（安全+同意+礼貌预算），再在可行集内最大化其余项。RUX 指数把 [任务恢复率, 打断率, 恢复时延, 解释可懂度, 信任校准误差, 控制感] 归一化后报告给用户与运维，**不参与安全判定**。

**定义 238（升级价值分析 EVA 与同意边界）** 决策
a*=argmax_{a∈{auto,ask,stop}} E[U(a)]，s.t. auto 仅当 ∃r: Valid(J_rec(r)) ∧ ρ_rev(r)≥ρ_min。
询问规则：ask 当且仅当
VOI = E_{o∼p(·|ask)}[max_{a′}U(a′)] − max_{a′}E[U(a′)] > c_int + c_delay
且 N_int < B_int；否则不打扰。不可逆动作无论 VOI 多大都必须显式同意（同意边界），这是对"效率"的硬性否决权。stop 当且仅当无认证恢复路线且询问无正价值（或用户缺席/超时）。EVA 把第 65 轮 AFA 的"主动判别"扩展成"**主动求助**"：探针不只问世界，也问人，但问人是有价格的。

**定义 239（可读解释 LEX 与宣告）** 解释 e 的目标不是"复述日志"，而是让用户能正确识别故障类别并选择下一步：
L(e)=P(Ĥ_user=H|e)+P(正确下一步动作|e)，在长度与认知成本约束下最大化 L(e)−λ_len·|e|−λ_cog·C_cog(e)。
模板固定为四段：(i) 发生了什么（触发通道与严重度）；(ii) 我为什么这么判断（证书/后验摘要，不暴露不可审计的内部特征）；(iii) 我将要做什么、是否可逆、预计多久；(iv) 你可以做什么（接管/同意/拒绝/改为停机）。宣告（announcement）是执行前发布的同一模板的机器可读版本；意外度
S = sup_s D(π_announced(·|s)‖π_executed(·|s))，
非紧急情形要求 S≤ε_surprise。

**定义 240（信任校准 TCM）** 真实可靠度 τ*=P(成功|上下文, 已宣告保证)，由 conformal/历史统计给出区间 [τ*_lo, τ*_hi]；用户信任 τ̂ 从行为估计（接受率、推翻时延、监控频率、是否逐步检查）。校准误差 e_τ=|τ̂−τ*|，并区分过度信任（τ̂≫τ*_hi）与不足信任（τ̂≪τ*_lo）。过度信任→提高解释粒度、展示失败模式、在 R2 前强制确认；不足信任→减少无效打断、展示可验证的自主边界。**禁止用降低安全或隐瞒失败率来"提升体验/信任"**；校准只改变信息呈现与权限分配，不改变硬约束。

**定义 241（恢复记忆库 RML 与负迁移防护）** 案例 c=(x_rec 上下文签名, post 故障后验, r 恢复路线, o 结果, cert_ver 证书版本)。检索时先做上下文 OOD 门：若 d_ctx(x_rec,x_now)>τ_ctx，则案例仅作"弱先验"，并计算负迁移风险 NT=P(outcome 不同|x_rec,x_now)。**任何被检索到的恢复路线都必须重新走 CRR 认证**，记忆只提供搜索起点，不提供安全结论。写入只在语义流、且在恢复结果与用户反馈都到达后进行；证书版本不匹配的案例不得直接复用。

**定义 242（恢复深度与终止）** 设第 d 次恢复尝试的边际效用 ΔU_d。在边际收益递减假设 E[ΔU_{d+1}]≤γE[ΔU_d]（0<γ<1）与每次尝试成本 c_att 下，最优深度
D*=min{D_max, min{d: E[ΔU_d]<c_att}}。
伤害预算按几何分配：α_rec,d=α_total·2^{−(d+1)}，保证 Σ_{d≥1}α_rec,d=α_total/2<α_total，为终止路径保留一半预算。所有尝试失败或恢复结果与所有假设都不符→判 `recovery_ambiguous`，执行最小可逆回退 + 人工移交，**禁止无限"恢复的恢复"**。

**定义 243（恢复盾 SRA）** 对每个候选恢复动作 a，实时盾检查硬约束集
𝒞_hard={f_n≤f_lim, strain≤ε_strain, |v|≤v_max, x∈𝒳_free, d_human≥d_min, q∈𝒬_joint}；
任一违反立即中止并回退到最近检查点。SRA 只允许派发 J_rec 认证前缀 k*_rec 内的动作；它不信任规划器的"意图"，只信任其"下一动作+当前状态"。SRA 的判定不依赖学习模型，只依赖可实时读取的物理量与几何。

**定义 244（恢复感知技能规划 RSP）** 在 CSP-V 的块级任务图上增加检查点/回滚锚点边与恢复宏边；每个普通块需在进入前显式记录 checkpoint。规划目标为最大化 EAU，硬约束为 Valid(J_rec)、安全裕度与同意。检查点间距 Δ 与恢复代价联立：过密则开销大，过疏则回滚损失大（见命题 4）。规划器可插入 `checkpoint`、`null_test`、`visual_probe`、`consent_gate` 元技能。

**定义 245（UX 契约）** 三条硬规则：
(i) **不静默失败**：任何 F 必须生成带原因码、严重度、可选项的用户可见事件，禁止把失败伪装成"重试中"。
(ii) **不制造意外**：非紧急情况下 S≤ε_surprise；执行前宣告动作、时长、可逆等级、升级选项；偏离必须在 τ_announce 内重新宣告。
(iii) **知情自主**：R2 动作需同意；R0/R1 动作可在已宣告的自主边界内自动执行；用户可随时把权限降到"仅停机"。
优先级严格为：安全 > 同意 > 体验 > 任务进度；低优先级项不得用于否决高优先级项。

**定义 246（用户模型与权限分配）** 用户偏好 w=(w_g,w_t,w_i,w_c,w_u) 可从反馈更新，但 w_s 固定为硬约束、不可学习下调；偏好更新有界（信赖域），防止产品指标把 w_i 推到"永不打扰"。权限级别 A∈{全自动, 可逆自动+不可逆询问, 全询问, 仅停机} 按 (风险, 不确定性, 可逆性) 分配：高风险或高不确定或 R2 集中→降权；反之在用户明确授权后升权。升权需显式同意，降权可自动。

**定义 247（REVIVE 证书 J_revive）** J_revive=(J_vista, recovery_cert, rev_budget, eau_terms, escalation_decision, interruption_count, legibility, trust_calib, recovery_depth, announcement_hash, aic_r_ver)。验证规则：
Valid(J_revive) ⇔ Valid(J_vista)
∧ (escalation_decision=auto ⇒ ∃r Valid(J_rec(r)))
∧ (存在 R2 动作 ⇒ consent_hash 非空且动作前已宣告)
∧ recovery_depth≤D_max
∧ 复用记忆中的路线已重新认证（cert_ver 匹配）
∧ N_int≤B_int ∧ (非紧急⇒S≤ε_surprise)
∧ aic_r_ver 为当前版本。
审计链新增：为什么选这条恢复（RCA+J_rec）、为什么自动/询问/停止（EAU/EVA）、用户被如何告知（LEX+announcement_hash）、恢复失败后为何停止（D*）。

**定义 248（REVIVE 闭环算子）** 语义流：[VISTA 归因→失败分类 F→RCA 候选 Γ(H)→RSP 检查点/回滚锚点→CRR 认证→EAU/EVA 决策→LEX 解释与宣告→执行 k*_rec→结果回灌 FIR-R→RML 写入/检索→TCM 更新→J_revive]；实时流：[残差采集→阶段判定→SRA 硬约束→恢复前缀派发→早停/回退→宣告事件→J_revive 构建]。

**定义 249（共因与双重故障下的恢复）** 当 (i) 故障后验仍不集中，或 (ii) 恢复结果与所有假设的预测都不符，或 (iii) 恢复本身触发新的安全事件（恢复诱发故障），不强行归因、不无限恢复；判 `recovery_ambiguous`，执行"最小可逆回退 + 保持安全 + 人工移交"，并把案例写入 RML 隔离区（不参与常规检索）。该规则显式对冲第 65 轮 A88：**恢复失败本身是"归因可能错误"的证据，而不是继续恢复的理由。**

**定义 250（失败后学习飞轮）** 用恢复结果 o 与用户反馈（接受/拒绝/解释评价）更新 Γ 先验、RCA 成功率、RML 案例与检查点策略；更新前须通过 AIC-R 回归（干扰集 ℰ_R=ℰ_V×{恢复诱发, 用户误操作/缺席, 恢复级联, 双重故障}）与分布漂移检测；实时执行使用固定证书版本与固定记忆版本，语义流更新通过版本切换原子生效，避免在线学习污染实时路径。

class RecoveryCapabilityAtlas:
    """故障假设 → 候选恢复；恢复原语携带可逆等级、代价与证书模板。"""
    def __init__(self, primitives, gamma_prior, aic_r_ver):
        self.prims = primitives            # {name: (pre, eff, rev, cost, cert_tpl)}
        self.gamma = gamma_prior           # P(r | H) 先验成功率
        self.aic_r_ver = aic_r_ver

    def candidates(self, F, post):
        out = []
        for H, p in post.items():
            if p < DELTA_SUPPORT:
                continue
            for r_name in GAMMA[H]:
                if not self.prims[r_name].pre(F, H):
                    continue
                out.append(Candidate(r_name, H, p * self.gamma[H][r_name],
                                     self.prims[r_name].rev,
                                     self.prims[r_name].cost))
        return dedup_sort(out)             # 按先验成功/代价排序，仅作候选

    def isolation_zone(self, case):
        # 未知/双重故障：只进隔离区，不参与常规检索
        return self._store(case, quarantined=True)

### IP-225 / IP-236 CRR（可逆性感知恢复证书）

```python
class CertifiedRecoveryRoute:
    def __init__(self, m_rec, B_irr, rho_min, alpha_total, delta=0.05):
        self.m_rec, self.B_irr, self.rho_min = m_rec, B_irr, rho_min
        self.alpha_total, self.delta = alpha_total, delta

    def certify(self, route, s, post):
        b_irr = sum(c for r, c in zip(route, cost(route)) if rev(r) == 'R2')
        if b_irr > self.B_irr:
            return Invalid('irreversible_budget')
        # 每层伤害预算按几何分配，为终止路径保留一半
        alpha_d = self.alpha_total * 2.0 ** (-(route.depth + 1))
        # 在最可能假设的支持集上验证认证前缀
        support = [h for h, p in post.items() if p >= self.delta]
        k_best, ok = 0, True
        for k in range(1, min(len(route.prefix), self.m_rec) + 1):
            for h in support:
                if safety_margin(route.prefix[k - 1], h, s) < 0:
                    ok = False
                    break
            if not ok or violation_prob(route.prefix[:k], support) > alpha_d:
                break
            k_best = k
        if k_best == 0:
            return Invalid('no_certified_prefix')
        rho = return_probability(route.prefix[:k_best], s)
        if rho < self.rho_min and not consent.granted(route):
            return Invalid('reversibility_or_consent')
        return Valid(prefix=k_best, b_irr=b_irr, alpha=alpha_d, rho=rho,
                     checkpoint=s.checkpoint)
```

class ExperienceAdjustedUtility:
    def __init__(self, w, B_int, eps_surprise):
        self.w = w                       # w_s 不在其中：安全是字典序约束
        self.B_int, self.eps_surprise = B_int, eps_surprise

    def __call__(self, a, post, pref, trust):

    def feasible(self, a, cert):

class EscalationValueAnalysis:
    def decide(self, post, s, pref, trust, depth):

        routes = rca.candidates(F, post)
        certified = [r for r in routes if crr.certify(r, s, post).valid]

## 4. 推导

**引理 9（恢复即检验）** 设真实故障为 H，恢复动作 r 在假设 H′ 下的结果分布为 p(o|H′,r)。若对所有 H′≠H 有 KL(p(o|H,r)‖p(o|H′,r))≥κ_rec>0，则 d 次独立恢复尝试的对数似然比在对角假设下是期望增量 ≥d·κ_rec 的下鞅，后验熵满足 E[H(H|o_{1:d})]≤H(H)−d·κ_rec+O(1)。因此恢复在修复任务的同时降低归因不确定性；反之若 κ_rec≈0（恢复结果对故障不可分辨，例如所有假设下重试都同样失败），恢复只能修复不能归因，不得据此强化后验。∎

**引理 10（可逆性受限的恢复安全）** 设恢复深度 d，每层伤害预算 α_rec,d=α_total·2^{−(d+1)}，则 Σ_{d=1}^{D_max}α_rec,d<α_total/2≤α_total；由联合界，整个恢复过程累计越界概率 ≤Σ_d α_rec,d≤α_total。若 b_irr=0，则每个动作都在 R0/R1 类，存在回检查点的策略，回退成功概率 ≥1−ε_rev；若 b_irr>0，则最坏伤害被 b_irr 与每动作硬上界 h_max 共同限制为 b_irr·h_max，且 B_irr 的选取使该上界不超过正常运行的最坏伤害预算。故恢复不引入超出正常安全集之外的新最坏情形。∎

**定理 9（REVIVE 端到端）** 在 A88–A98（A94 恢复可分辨、A95 可逆性界、A96 用户代价可估、A97 安全与同意为字典序约束、A98 记忆漂移可检测）下，若 Valid(J_revive)，则：
1. **失败被闭环处理**：每个 F 要么进入认证恢复、要么进入询问、要么进入终止安全态；不存在"失败后无决策"的状态（定义 234/248）。
2. **恢复伤害受控**：auto 路线满足 P(伤害)≤α_rec 且 b_irr≤B_irr（引理 10）。
3. **知情自主**：任何 R2 动作都有 consent_hash 且执行前已宣告；无静默失败，非紧急意外度 ≤ε_surprise（定义 245/247）。
4. **归因可被证伪**：恢复结果回灌 FIR-R；若 κ_rec>0 则后验改善，否则判 `recovery_ambiguous` 并停止级联（引理 9/定义 249）。
5. **用户代价有界**：N_int≤B_int，恢复深度 ≤D*≤D_max（定义 237/242）。
6. **体验不削弱安全**：因 w_s 与同意为字典序硬约束，EAU 只能在可行集内改变 auto/ask/stop，不能放行不安全动作（命题 1）。∎

**定理 10（升级与停止的阈值最优性）** 设每个决策的 EAU 可分、VOI 关于后验不确定性单调、恢复边际收益递减（E[ΔU_{d+1}]≤γE[ΔU_d]）。则 EAU 最优策略具有阈值形式：(i) 存在认证可逆路线时自动恢复；(ii) 仅当 VOI>c_int+c_delay 且 N_int<B_int 时询问；(iii) 当无认证路线且询问价值不足时停止；(iv) 恢复深度在首个 E[ΔU_d]<c_att 处截断，且 D*≤D_max。证明：对 auto/ask/stop 三选项，EAU 的差值是 VOI 与 (c_int+c_delay) 的符号函数，故阈值由符号变化点给出；深度由递减序列的部分和最大化给出，首次负边际即为停止点；D_max 为硬上界。∎

**命题 1（UX 不削弱安全）** 若实现严格采用字典序约束（安全 → 同意 → 体验 → 进度），则对任意 UX 权重 w 与任意偏好更新，可行集 𝒜_feas={a: Harm(a)≤α_rec ∧ (R2⇒consent)} 不变；优化仅改变 𝒜_feas 内的选择。因此改变 w 不会使任何不安全动作变为可选。**该命题不成立当且仅当工程上把安全退化为有限罚项 w_s·Harm**——这正是第 7 节的头号风险。∎

**命题 2（恢复可分辨性的充分条件）** 若存在恢复动作 r 使对 H≠H′ 有 ‖p(o|H,r)−p(o|H′,r)‖_TV≥ε_rec，则 κ_rec≥2ε_rec²（Pinsker 下界），从而引理 9 成立。实用含义：RCA 应优先选择**结果分布差异大**的恢复原语，而不是"最可能成功"的原语；这与第 65 轮 AFA 的"最大互信息"一脉相承，但把信息源从物理探针扩展到恢复结果。∎

**命题 3（询问的边际收益上界）** 在用户回复的信息量受限于二分类诊断（正确/错误）且正确率 p_u 时，VOI≤H_b(p_u)·ΔU_max，其中 H_b 为二元熵。故当 c_int+c_delay>H_b(p_u)·ΔU_max 时询问必不划算；这给出了"何时闭嘴"的可计算上界，避免 EVA 在高打断成本下仍频繁求助。∎

**命题 4（检查点间距权衡）** 设单位进度检查点开销 c_ckpt/Δ、故障率 p_f、回滚代价 c_roll·Δ/2（平均回退半个间隔），则单位进度期望代价
c(Δ)=c_ckpt/Δ + p_f·c_roll·Δ/2，
最优间距 Δ*=sqrt(2c_ckpt/(p_f·c_roll))。
故 RSP 不应把检查点设得越密越好；它应随故障率与回滚代价自适应。∎

## 7. 已知风险

**一句话**：把用户体验写进目标函数，等于在安全约束旁开了一个可交易的缺口——一旦打断成本、信任或"用户不想被打扰"被误估或被产品指标人为调低，系统就会用它来为跳过恢复认证、延迟升级、静默重试辩护，安全便从硬约束退化为效用项；而本轮"UX 不削弱安全"的命题恰恰只在 w_s 与同意是真正硬约束时才成立。

**次级风险与缓解**：
1. **UX 被当作安全的可交易项**：主风险。缓解：字典序实现（安全→同意→体验→进度）、w_s 不进优化器、代码级断言 `feasible()` 先于打分、AIC-R 中加入"高打断成本 + 不安全恢复"对抗用例。
2. **用户代价模型误设**：c_int、c_delay、C_cog 依人依情境变化。缓解：在线学习但有界（信赖域），每次只用用户显式反馈更新；异常时退回保守默认值；EAU 报告置信区间而非点估计。
3. **同意疲劳 / 打断疲劳**：频繁 R2 请求会训练用户盲点"同意"。缓解：礼貌预算 + 同意合并 + 只在不可逆且高风险时请求 + 提供"本次任务内不再询问"的可撤销授权；监测同意时延与同意后的推翻率。
4. **信任校准被当成操纵工具**：产品可能用"少报失败率"提升 τ̂。缓解：TCM 只读不可写安全相关日志；诚实保证区间由 conformal 给出，禁止编辑；审计链保留 announcement_hash 与真实结果。
5. **恢复记忆负迁移**：表面相似上下文导致错误复用。缓解：上下文 OOD 门 + 负迁移估计 + 复用必重新认证；隔离区不参与常规检索。
6. **恢复结果对故障不可分辨**：κ_rec≈0 时恢复不能归因，可能强化错误后验。缓解：预计算 Γ 的可分辨性；低分辨恢复只用于修复，不更新归因；判 `recovery_ambiguous`。
7. **恢复诱发新故障 / 双重故障**：恢复动作离开安全集，可能触发未建模动力学。缓解：SRA 硬约束 + 每层几何伤害预算 + D_max + 终止安全态；AIC-R 显式注入恢复级联。
8. **解释幻觉**：生成式解释可能编造原因。缓解：LEX 只从证书与后验模板生成，不自由发挥；数字必须带来源哈希；AIC-R 增"解释与证书一致性"检查。
9. **实时预算**：SRA 与宣告事件逼近 2.8ms。缓解：约束预编译、检查点缓存、事件相机触发、把 CRR/EAU/LEX/RML 全部留在语义流。
10. **用户缺席 / 延迟**：ask 决策在无人响应时退化为等待。缓解：ask 带超时，超时后按预授权策略退到 stop_safely；预授权只在 R0/R1 生效，R2 永不预授权。
