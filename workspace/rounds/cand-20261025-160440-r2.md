# 第 8 轮 · INTENT-DP：扩散是「怎么落」，意图是「落在哪」，落地是「什么时候多算一点」

> 检索/复核日期：2026-10-25（UTC）。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「扩散策略」「意图理解」「场景落地」。我先用官方规则、接口文档和头部模型的公开资料把这三个词钉到本轮的新事实上，再给一个可能比第 7 轮更锋利的判断：**20–30% 的天花板不是动作生成能力不够，而是「意图→3D 目标→落地」的三段损失：模型能把动作做得像，但在 OOD 场景里不知道「落在哪、以什么姿态落、被打断后怎么重来」；头部模型 MolmoAct2 自己承认是 10–30 步开环批量执行，正好被人为干扰轴打穿。扩散策略的价值不只是「多模态动作头」，而是它能给出一个可采样、可验证、可按剩余时间分配算力的「目标分布」；意图理解的价值不只是「读懂句子」，而是把公开评分细则编译成可 grounding 的类型化程序；场景落地的价值不只是「部署工程」，而是把 180 秒、N 端口、固定 chunk、动作规律性这些契约变成策略的一部分。**

## 0. 本轮先核实：五个会改变判断的新事实

### 0.1 排名规则是「成功率优先，步骤分只做 tie-break」

官方参赛手册（[S1]）写得很清楚：

> 实时榜单按 32 个任务的 **总平均成功率** 进行排序，成功率相同时按总平均步骤分排序，若仍相同，则提交日期较早的模型排序靠前。

这句话把第 7 轮的一个核心论证修剪掉了。第 7 轮说「终局步骤占 39.8%、放置类占 59.7%，所以放置是最大单项」——这个算术没错，但**步骤分不是主目标，只是平分时的第二关键字**。真正的主目标是：

```text
max (1/32) Σ_t P_t,   P_t = P(该任务 10 次运行全部步骤完成)
```

终局步骤之所以是闸门，不是因为它的权重 40 分，而是因为**成功 = 所有步骤完成**。所以第 7 轮的「放置优先」结论保留，但理由要换：不是「它分值最大」，而是「它是成功闸门，且跨五轴同时起作用」。步骤分仍然有用——它是诊断「钱丢在哪一步」的探针，也是平分时的第二关键字——但不能再用它来给目标函数加权。这是本轮第一个重要修剪。

### 0.2 每个任务 10 次，5 类泛化各 2 次；这是 32 个任务的等权组合，不是 320 次独立抽样

同一份手册（[S1]）：

> 每个任务执行 10 次独立运行，每次运行采用不同的泛化设定……10 次运行中包含以下 5 种泛化类型，每种类型各出现 2 次。

这意味着：

- 每个任务的成功率是 10 次运行的均值；总榜是 32 个任务均值的再平均（宏平均）。**每个任务等权 1/32**，不管它难还是易。
- 每个泛化轴在一个任务内只占 2/10；轴级估计的噪声很大（2 次运行），**不能拿单轴数字做精细排名**，只能做诊断。
- 因为任务是等权的，**「填谷」比「抛光」更划算**：把一个 5% 的任务提到 25%，平均分 +0.625pp；把一个 30% 的任务提到 40%，只 +0.3125pp。第 7 轮的「跨轴杠杆」仍然成立，但本轮要再加一个「跨任务杠杆」：**先找真实榜单/调试槽里最接近 0 的任务，而不是继续在已经 30% 的任务上抠 1–2pp**。
- 180 秒/任务、10 次/任务、32 任务 = 最多 320 次真机 episode。任何「每次多花 2 秒验证」的设计，乘上 320 次就是 640 秒的评测预算；但单次 180 秒内的余量仍然充足（演示中位数约 6–10 秒）。所以「落点闭环」在单任务内可行，但不能让长程任务的重试次数失控。

### 0.3 接口契约和数据集契约不一致：这是一个被低估的落地坑

我本轮把 `unibot_submission` 的 README（[S3]）和 HangCup 数据集的 `meta/info.json`（[S4]）逐键对了一遍，发现训练数据和推理 API 并不是同一套观测：

| 数据集有 | API 有 | 结论 |
|---|---|---|
| `observation.images.head_stereo_left/right` | `observation.images.cam_left_high/right_high` | 名字不同，需映射；是否是同一对标定双目未核实 |
| `observation.images.wrist_left/right` | `observation.images.cam_left_wrist/right_wrist` | 名字不同，需映射 |
| `observation.state.left/right_ee_pose_gripper_base` | 同名 | 可用，base 系 |
| `observation.state.left/right_ee_pose_gripper_torso` | **没有** | 训练时不能用 torso 系 |
| `observation.state.state_torso` | **没有** | 训练时不能用 |
| `observation.state.state_d435` | **没有** | 不能依赖 D435 外参 |
| `observation.state.left/right_leg` | **没有** | 不能依赖腿关节 |
| `observation.state.waist_state_joint` | **没有** | 不能依赖腰关节 |
| `action.lower_body` | `action.pivot` [7] | 动作键不同，需映射 |
| `action.left/right_leg`、`action.waist_action_joint` | **没有** | 不能训练这些动作头 |

这不是小事。一个在 33k 演示上训得很好的模型，如果隐式用了 `state_torso`、`state_d435`、`left_ee_pose_gripper_torso` 或腿/腰关节，到了 API 就会分布外。更隐蔽的是：**API 只给 RGB，没有深度**；数据集里的 `state_d435` 只是相机位姿，不是深度图。所以推理时的 3D 信息只能来自双目（如果 `cam_left_high/right_high` 是标定双目）或单目深度估计。第 7 轮假设「四路 RGB + EE 位姿足够」，方向对，但**必须做 contract-aligned training：训练时只喂 API 会给的键，base 系 EE 位姿，双目/单目深度，绝不喂特权键**。这是一个便宜、可验证、可能直接解释一部分 20–30% 天花板的工程点。

### 0.4 榜单还是「预览态」，但模型家族是真实的，结构信息可用

`leaderboard.html` 现在能读到 8 个模型（[S2]）：MolmoAct2/DexHacker 29.7%、WALL-OSS-0.5/Generalist Robotics 28.5%、DreamZero/World Model Lab 27.9%、Spirit-v1.5/VLAGO 25.9%、DM0 23.5%、PI-0.5 22.8%、GigaBrain-0 22.6%、GR00T N1.5 20.5%。但：

- 首页仍写「即将发布 / Coming Soon」；
- `details.html` 的 32 个任务视频全部是「测试视频占位，后续可替换为真实视频文件」；
- `leaderboard_data.json` 的 `generated_from` 是 `gen_leaderboard.py`，`runs.html` 是 256/256 条记录、视频占位。

所以这些数字**不能当作真实排名**，只能当作「预览先验」。但模型家族是真实的：MolmoAct2（Ai2，[S6]）、WALL-OSS-0.5（X Square Robot，[S7]）、DreamZero（NVIDIA GEAR，[S8]）都是公开可查的模型。三个架构差异很大的模型挤在 27.9–29.7% 的 1.8pp 内，这比「谁第一」更有信息量：**共享瓶颈大概率不在动作头架构，而在数据/场景/意图 grounding**。这也是本轮判断的起点。

### 0.5 头部模型自己承认的弱点，正好是人为干扰轴要打的点

MolmoAct2 的官方博客（[S6]）写了两条弱点：

> First, rather than reacting continuously, it plans a batch of 10-30 moves and executes the whole sequence without inferring again. The robot can't adjust mid-batch if something unexpected happens, like bumping into an obstacle... Second, the model only works out of the box on the robot setups it was heavily trained on: SO-100, bimanual YAM, and Franka. Using it on a different platform, like a humanoid or a hand-equipped robot, requires additional training.

这两条几乎是 UniBot 的定制攻击面：

- **人为干扰轴**（每任务 2/10 次）会在 episode 中途移动物体/撤销步骤/拿走目标；开环 10–30 步批量执行无法在中途反应，正好被打穿。
- **G1 + Dex1** 是 MolmoAct2 没有重点训练的人形+手平台；跨 embodiment 的适配本身就会掉点。

WALL-OSS-0.5 的公开信息则是另一面（[S7]）：4B VLA、3B VLM backbone、离散动作 token + 连续 flow matching、20+ embodiment、100 万+ 轨迹/epoch。它的强项是通用先验和部署友好；弱项可能是**没有显式的任务相位/意图状态**，在长程多步任务里容易「做对动作但做错顺序/目标」。DreamZero（[S8]）是 14B 世界动作模型、视频扩散、7Hz 闭环、零样本泛化强；但 14B 的部署成本和 7Hz 的控制频率，在 N 端口 + 180 秒的评测里是硬约束。三者合起来看：**动作生成不是唯一瓶颈，意图/相位/落点/反应性才是。**

## 1. 三个灵感词，各自钉到本轮事实上

### 1.1 扩散策略：不是「换个动作头」，是「把目标做成可采样、可验证的分布」

第 7 轮的 OPT 用的是「K 条演示释放位姿的中位数」。这能处理单峰放置，但处理不了多峰：同一个「把碗放到中间」可能有多个可行落点/朝向；同一个「插头插入第一个插座」需要毫米级姿态；同一个「叠碗」需要碗沿对齐。中位数会把多峰平均成一个不存在的中间点。扩散模型天然适合这个：

- **慢扩散（SGD）**：在相位边界上，以场景图 + 意图 + 相位为条件，采样 M 个 6D 目标位姿（base 系），用碰撞/可达/稳定/关系谓词打分，取 top-1；用样本离散度估计「这个目标有多不确定」。
- **快扩散（FAD）**：以当前观测 + 目标 overlay + 意图 + 相位为条件，用 flow matching 生成动作 chunk；蒸馏到少步，保证 10Hz 级推理。
- **算力分配（ACA）**：慢扩散只在相位边界跑；快扩散每步跑。M/N/步数不是固定的，而是按「这个相位失败会不会毁掉整个任务」和「还剩多少秒」来分配。这正是 ELASTIC（[S11]）和 DA-SIP（[S12]）证明有效的方向：测试时算力可以沿「并行采样」和「串行去噪」两轴分配，学出来的调度能在匹配成功率下把延迟降 34%，或在匹配算力下 Pareto 占优。我们的不同点是：**分配信号不是通用难度分类器，而是公开评分细则的相位风险 + 扩散样本一致性 + 剩余 180 秒**。

为什么不是「直接上更大的扩散 VLA」？因为 MolmoAct2/WALL-OSS/DreamZero 已经把动作生成做到了很强的水平，仍然只有 20–30%。扩散的边际价值在**目标层**（多峰落点、姿态、插入深度）和**算力层**（哪里值得多算），而不是把动作头再加大。

### 1.2 意图理解：不是「读懂复述」，是「把评分细则编译成可 grounding 的程序」

数据集里每个任务有 5 条英文复述（[S4]，本轮用 `strings` 重新确认 HangCup 的 5 条：marked spot / marked position / Hook ... onto ... / marked place / marked position）。这 5 条其实很相似，真正难的不是复述，而是**组合指代**：

- T06：指令说「从右到左按红、绿、黄排列」，评分步骤说「红在最右、绿在中间、黄在最左」。模型必须把「顺序 + 轴 + 颜色」三元组解成三个位置。
- T27：指令说「按红、绿、蓝的顺序叠三个碗」，评分步骤说「碗 1 放中间、碗 2 叠碗 1、碗 3 叠碗 2」。模型必须把颜色序映射到叠放序。
- T04：「放到颜色匹配的盘子里」——属性匹配 + 目标选择。
- T08：「把最上面的书放到书架」——最高级 + 目标容器。
- T24：「按类别放到货架对应位置」——类别识别 + 映射。
- T10：「把插头插到第一个插座」——序数 + 插入关系。

这些都不是「语言 embedding 不够大」能解决的，而是**语言→场景实体/关系/目标的 binding**。Spa-Bench（[S15]）给了直接证据：真机空间 grounding 在 ID 67.5–73.3%，OOD 掉到 40.7–52.0%；把空间指令换成直接操作指令，成功率 +28–40pp。Counterfactual Instruction Grounding（[S16]）和 Anchor-Align（[S17]）也说明：VLA 在窄域微调后会变得「视觉反应式」，指令敏感性下降；需要反事实/锚定式训练才能保住 grounding。

所以本轮的「意图理解」分三层：

1. **任务意图（RIC）**：把 32 个任务 × 5 条复述 + 评分步骤编译成类型化程序：每个 phase 有 action、object ref（类别/颜色/序数/属性）、target ref（容器/标记/区域/关系）、constraints、success predicate、weight。离线用 LLM 编译 + 人工核对 160 条；推理时精确/模糊匹配，不跑 LLM。
2. **场景意图（SGG）**：用四路 RGB + 双目/单目深度 + 本体，构建场景图；用关系求解器解析 leftmost/middle/top/matching color/designated spot/ordinal；输出 base 系 6D 目标和 2D overlay。低置信时回退到演示目标检索。
3. **干扰意图（IIU-R）**：官方 human_1/human_4 备注（[S5]）本质上是一套「人类干扰剧本」：平移目标、撤销上一步、拿走物体、遮挡、移动容器、干扰运动目标。把这些归成 6 类原语，训练一个轻量分类头；检测到场景图异常变化时，推断「人类想干什么」，选择 resume/reground/redo/regrasp/wait。这是把「人为干扰」从噪声变成可解释的信号。

第 7 轮的 SSG 是「评分步骤状态机」，本轮升级成 RIC：不只是状态机，而是**可 grounding 的类型化意图程序**；第 7 轮的 NRB 是「训练时回放备注」，本轮升级成 IIU-R：**推理时识别干扰意图并选择恢复策略**。这是深化，不是推翻。

### 1.3 场景落地：不是「把服务跑起来」，是「把契约变成策略的一部分」

本轮读接口文档（[S3]）读出了几个会直接影响策略的硬约束：

- `action_chunk_size` 是 metadata 里的**固定整数**，不是每次调用可变。所以「自适应 chunk 长度」不能按字面做；正确做法是**固定 chunk 长度 + 不确定性门控的 chunk 内容**：高不确定时，chunk 的后半段填「保持/刹车/保守续接」，下一次调用再重规划；低不确定时填满完整计划。这是一个很重要的接口细节，第 7 轮的 SVL 没有考虑。
- `obs_delta_indices` 和 `image_resize` 也是**固定**的；观测历史、图像分辨率在整次提交内不能变。所以要在离线就选好：图像堆叠 [-10,-5,-2,0] 还是 [-4,-2,0]；头相机 240×320 还是 480×640；腕相机 128×128 还是 240×320。这些选择直接影响延迟、显存和 grounding 精度。
- `control_space` 是 `joint` 或 `ee`，**互斥且固定**。EE 空间适合「目标位姿迁移」，joint 空间可能更适合接触丰富任务；必须用调试槽做一次 A/B，不能拍脑袋。
- **N 个端口连续 8765..8765+N-1**，每个端口独立 episode、独立状态；共享模型要处理并发，且延迟/动作规律性会被记录。这意味着「一个模型 + N 个无状态副本」比「一个共享后端 + 动态批处理」更容易控制延迟方差；如果显存不够，至少要做 per-port 状态隔离和请求队列。
- 评测会记录**每步响应延迟及其方差、返回动作的统计规律性**，并可能随结果展示（[S3] §6）。所以扩散采样的随机抖动、chunk 切换的跳变、异常 outlier 都会被看见。动作平滑不是「锦上添花」，是 credibility 的一部分。

这些约束把「场景落地」从工程降级为**策略的一部分**：延迟预算决定 chunk 长度和观测分辨率；动作规律性决定采样器和融合方式；N 端口决定部署拓扑；180 秒决定算力分配。第 7 轮把 FLEET 降级为检查单是对的，但本轮要把它升级成**契约感知的运行时**（CAT + ACA + ETR），而不是简单的部署清单。

## 2. 本轮主判断：20–30% 是「意图→目标→落地」的三段损失，不是单点问题

把上面的证据合起来，我给一个更锋利的失败模型：

```text
P(成功) = P(意图解析对) × P(目标 grounding 对) × P(落点/插入执行对) × P(干扰后恢复对) × P(在 180s 内完成)
```

头部模型大概在前两项和最后一项上丢分最多：

| 损失段 | 证据 | 本轮对策 |
|---|---|---|
| 意图解析/指代绑定 | Spa-Bench OOD grounding 掉 20–30pp；T06/T27 的组合指代 | RIC + SGG |
| 目标 grounding（多峰/姿态） | 放置/插入是终局闸门；中位数会平均掉多峰 | SGD（慢扩散）+ 目标 overlay |
| 执行/落点精度 | 步骤分比成功率高约 8.6pp（预览数据，弱先验） | FAD + 谓词校验 + 缓放 |
| 干扰后恢复 | 官方备注多为平移/撤销；MolmoAct2 开环 10–30 步 | IIU-R + UGCC + ETR |
| 时间/算力 | 180s、N 端口、延迟被记录 | ACA + CAT |

**一句话：不是「动作不够好」，是「目标不够清楚、落点不够稳、被打断后不会重来」。** 扩散策略负责「把目标做成分布并采样」，意图理解负责「把目标说清楚并绑定到场景」，场景落地负责「在契约内把这件事稳定地跑完」。

## 3. 与第 7 轮的关系：保留骨架，换掉主武器

| 关系 | 内容 |
|---|---|
| 保留 | WLA-1.0-Base / GPR-VLA 底座、TLE/ACP/GF 数据引擎、AH-TP、Endurance Governor、Compliance Compiler、DebugLoop |
| 升级 | SSG → RIC（类型化意图程序）；PGL → SGG（场景图 + 关系求解 + overlay）；OPT → SGD（多峰目标扩散，中位数降为 fallback）；SVL → 谓词校验 + UGCC；NRB → IIU-R（推理时干扰意图 + 恢复） |
| 新增 | CAT（contract-aligned training）、FAD（快扩散动作头）、ACA（算力分配）、ETR（事件触发运行时）、TPD（任务组合诊断）、ICP（意图对比训练） |
| 降级 | ICR（从主路径降为「目标图像/位姿检索 fallback」）；L2L（从主路径降为可选数据多样性）；TCLB（离线相对比较） |
| 修剪 | 「步骤分占 60%」作为主论证；「终局权重 39.8%」作为主论证；全 32 任务高保真孪生；每任务 LoRA；FLEET 作为「第六轴」；自由仿真数据；运行时 MPC |

## 4. 方案轮廓：INTENT-DP

```text
语言（32 规范描述 + 160 复述 + 中文映射）
        │
        ▼
RIC：评分细则 → 类型化意图程序（phase/action/object/target/constraint/predicate）
        │
        ▼
SGG：4×RGB + 双目深度 + 本体 → 场景图 → 关系求解 → base 系 6D 目标 + 2D overlay
        │
        ├──► SGD（慢扩散）：多峰目标位姿采样 M 个 → 碰撞/可达/稳定/谓词打分 → top-1 + 不确定度
        │
        ├──► FAD（快扩散）：obs + overlay + intent + phase → 动作 chunk（flow matching，少步蒸馏）
        │
        ├──► UGCC：样本一致性 + 场景变化 + 相位风险 → 固定 chunk 内的「执行/保持/刹车」内容
        │
        ├──► IIU-R：场景图异常 → 干扰原语分类 → resume/reground/redo/regrasp/wait
        │
        └──► ACA：相位风险 × 剩余 180s → 分配 M/N/步数；低算力时回退确定性 primitive
        │
        ▼
谓词校验（RIC 的 success predicate）→ 通过则进下一 phase；不通过则诊断/重试
        │
        ▼
ETR：N 端口、状态隔离、异步计算、p99 延迟守卫、动作融合、健康检查
```

**核心不是某一个模块，而是「慢扩散出目标、快扩散出动作、意图程序做门控、算力分配做取舍」的分工。** 这比第 7 轮的「状态机 + 中位数位姿 + 检索上下文」更符合「目标多峰 + 执行实时 + 评测限时」的实际结构。

## 5. 本轮最值得押注的三件事（以及为什么不是别的）

1. **SGD（慢扩散目标）**：它直接攻「终局闸门 + 多峰落点 + 姿态/插入深度」，而且不需要新数据（33k 演示的释放位姿就是监督）。它是「扩散策略」在本赛事里最合适的落点——不是把动作头换成扩散（头部模型已经这么做了），而是把**目标**做成扩散分布。
2. **RIC + SGG（意图程序 + 场景 grounding）**：它直接攻 OOD 五轴里最共性的「语言→实体/关系/目标」绑定，且是确定性的、可解释的、可离线验证的。它是「意图理解」在本赛事里最合适的落点——不是让 VLM 再大一点，而是把公开评分细则变成结构化先验。
3. **UGCC + IIU-R（固定 chunk 内的反应性 + 干扰恢复）**：它直接攻 MolmoAct2 自己承认的开环弱点和 human 轴，而且完全在 API 契约内（固定 chunk 长度、固定观测、固定控制空间）。它是「场景落地」在本赛事里最合适的落点——不是堆部署工程，而是把「什么时候该停/重来」变成策略。

不押「更大的世界模型」：DreamZero 已经证明 WAM 的零样本泛化强，但 14B/7Hz 在 N 端口 + 180 秒里是硬约束；本轮把世界模型降为**离线教师/反事实生成器**（可选），不进主推理路径。不押「每任务微调」：单模型规则 + 评测 OOD 使收益存疑；不押「全 32 任务孪生」：成本高、保真度低，调试槽更可信。

## 6. 风险与合规（先立后破）

- **单模型边界**：RIC 是确定性代码/JSON；SGG 的关系求解是确定性代码；SGD/FAD/IIU-R 是同一 backbone 上的多个头（或同一 checkpoint 内的层级策略）。如果官方把「多个学习模块」视为多模型，需在模型卡披露并准备蒸馏版（把 SGD 蒸进 FAD，或退化为确定性采样）。这是本轮最大的合规风险。
- **外部数据/仿真**：仍未知（手册 2.2 之后没读到）。默认只用官方 33k + 对官方数据的 2.5D 编辑；L2L 合作数据默认 OFF；Isaac 只做可选的反事实生成，不进训练除非确认允许。
- **双目未标定**：`cam_left_high/right_high` 是否同一对标定双目未核实；若是独立相机，深度只能用单目估计，SGG 的 3D 精度会下降。回退：用演示目标检索 + 腕部视觉伺服。
- **慢扩散延迟**：M 个样本 × 去噪步数可能吃满 180s；必须在相位边界跑、缓存、蒸馏；p99 超预算就退化为中位数/检索。
- **动作规律性**：扩散采样抖动 + chunk 切换跳变会被记录；用确定性采样、时间集成、jerk 惩罚、动作裁剪。
- **调试槽稀缺**：每个大版本最多 1 槽；把调试槽当「发布门」，不是「调参器」。
- **统计噪声**：320 次运行、p≈0.3、SE≈2.56pp；轴级只有 2 次/任务，不能过度解读。用配对场景 + bootstrap。

## 7. 一句话押注

**把公开评分细则编译成类型化意图程序，用「慢扩散出多模态落点、快扩散出动作、按不确定性分配测试时算力」的两级扩散策略，在 180 秒和 N 端口契约内把落点闭环做扎实——这是本轮最值得押注的方向。**

## 1. 事实核对（本轮新增，全部一手；来源表见 §10）

### 1.1 官方规则：成功率优先，步骤分 tie-break；10 次/任务；5 轴 ×2；180 秒

中文手册（[S1]）原文：

> 比赛仅设有针对人形机器人泛化操作评测体系的多任务通才模型（Multi-task）赛道……通才模型赛道：要求参赛选手提交的模型完成全部的 32 个任务，每个任务在不同的泛化评测场景中进行 10 次测试，计算每个任务的平均成功率，平均过程分，并计入排行榜。
>
> 实时榜单按 32 个任务的 **总平均成功率** 进行排序，成功率相同时按总平均步骤分排序，若仍相同，则提交日期较早的模型排序靠前。
>
> 每个任务执行 10 次独立运行……10 次运行中包含以下 5 种泛化类型，每种类型各出现 2 次：位置泛化、干扰物泛化、桌面背景泛化、未见物品泛化、人为干扰泛化。
>
> 每个任务单次真机执行最大允许执行时间为 **180 秒**，超时记为失败，并根据执行情况计算步骤分，计入排名。

英文手册（[S1b]）一致：

> The real-time leaderboard is sorted by overall average success rate across all 32 tasks. In the event of a tie, the overall average step score is used as the differentiator. If still tied, earlier submission dates rank higher.

**推论（本轮核心修剪）**：

```text
主目标 = max (1/32) Σ_t P_t
P_t = P(任务 t 的 10 次运行全部步骤完成)
步骤分 = (1/32) Σ_t (1/10) Σ_r Σ_i w_{t,i} 1[phase i 完成]
```

步骤分只在成功率相同时决定名次；它不是主目标。第 7 轮的「终局步骤 39.8%、放置类 59.7%」仍然是对的，但只能作为**诊断权重**和**tie-break 考虑**，不能作为目标函数权重。终局步骤是闸门，因为成功 = 所有步骤完成，而不是因为它的分值最大。

### 1.3 头部模型的公开架构与自认弱点

**MolmoAct2（榜首 29.7%）**（[S6]）：

- 底座：Molmo 2-ER（在 Molmo 2 上继续训练约 300 万具身推理样本：pointing、detection、抽象空间推理、多图推理、图像/视频空间 QA）。
- 动作头：flow matching action expert，通过 KV-cache bridge 接 VLM；开放 FAST tokenizer。
- 速度：单次 action call 约 180ms（base）/790ms（adaptive depth reasoning），比 MolmoAct 的 6.7s 快 37×。
- 自认弱点 1：**plan a batch of 10–30 moves and executes the whole sequence without inferring again**；batch 中途不能调整，chunk 切换可能 jerk。
- 自认弱点 2：只在 SO-100、bimanual YAM、Franka 上开箱即用；G1 这类 humanoid/hand 平台需要额外训练。

**WALL-OSS-0.5（第二 28.5%）**（[S7]）：

- 4B VLA（3B VLM backbone + action-generation components）。
- 离散 action token（FAST 类）+ 连续 flow matching 双路径；离散路径给 VLM 梯度桥，连续路径做部署时动作接口。
- 20+ embodiment、100 万+ 轨迹/epoch；强调「pretrained capability 可直接在真机上测量」。
- 公开报告：15 个真机任务平均 task progress 60.5%，超过 π0.5；但这是 task progress，不是 UniBot 的成功率。

**DreamZero（第三 27.9%）**（[S8]）：

- 14B World Action Model（WAM），基于预训练视频扩散 backbone；联合预测未来视频与动作。
- 实时闭环 7Hz；零样本泛化到新任务/新环境；30 分钟 play data 可做 few-shot embodiment adaptation。
- 优势：物理动力学/新运动泛化；约束：14B 部署成本、7Hz 控制频率、对精确接触任务的优势仍需验证。

**共同结构**：三个架构差异很大的模型挤在 1.8pp 内，说明**共享瓶颈不在动作头架构**。MolmoAct2 的 explicit spatial reasoning、WALL-OSS 的 flow matching + 大规模跨 embodiment 预训练、DreamZero 的视频世界模型，都没有把成功率推过 30%。这支持「意图/目标 grounding + 反应性 + 数据/场景覆盖」是更大概率的瓶颈。

4. 相机名映射：`head_stereo_left/right` → `cam_left_high/right_high`；`wrist_left/right` → `cam_left_wrist/right_wrist`。如果物理相机不同，需要颜色/分辨率/视角增广，并用调试槽验证。

### 1.5 接口的硬约束（会改变策略设计）

| 约束 | 原文/事实 | 设计含义 |

## 2. 诊断：20–30% 的三段损失

### 2.1 目标函数与闸门

官方规则下：

```text
S = (1/32) Σ_t P_t
P_t = P(phase 1 成功 ∧ phase 2 成功 ∧ … ∧ phase K_t 成功)
    = Π_i P(phase i 成功 | phases <i 成功)
```

终局 phase 是闸门：无论它权重 20 还是 50，只要它失败，整个任务失败。第 7 轮的「终局步骤 39.8%」只是说终局在步骤分里占比大；真正的排名影响来自「它是最后一个 AND 条件」。

### 2.2 五轴扰动的是「意图→目标」映射，不是低层动力学

| 泛化轴 | 改变了什么 | 典型失败 | 对策 |
|---|---|---|---|
| 位置 | 物体初始位置/目标区域位置 | 抓空、放错槽位、关系解析错 | SGG 关系求解 + SGD 场景条件 |
| 干扰物 | 场景多出无关物体 | 抓错物体、路径碰撞 | RIC 目标指定 + 场景图过滤 |
| 背景 | 桌布颜色/纹理 | 视觉 encoder 过拟合背景 | 物体中心裁剪 + 背景增广 + 深度/几何 |
| 未见物品 | 同类但外观不同 | 颜色/实例记忆失效 | 类别级 object ref + 几何 affordance |
| 人为干扰 | episode 中途移动/撤销/拿走 | 开环执行不反应、假完成 | IIU-R + UGCC + 谓词重校验 |

五轴都不改变「机器人怎么动」的低层动力学；它们改变的是**语言指代绑定的对象/目标/关系**，以及**执行过程中目标是否还成立**。这解释了为什么不同动作头架构都卡在 20–30%：动作先验是共享的，grounding/反应性是共同的短板。

### 2.3 证据链

- **Spa-Bench**（[S15]）：真机空间 grounding ID 67.5–73.3% → OOD 40.7–52.0%；把空间指令换成直接操作指令，成功率 +28–40pp。说明「知道怎么动」不等于「知道往哪动」。
- **MolmoAct2 自认**（[S6]）：10–30 步开环批量，中途不能调整；human 轴正好打这个。
- **HINT**（[S10]）：语义意图在 manipulation-pattern 转换处稀疏变化，连续控制主要依赖 object-hand 关系；在转换点做语义推理、其余时间做视觉跟踪，比每步都推理更稳。支持「意图在相位边界更新 + 快策略持续执行」。
- **Counterfactual Instruction Grounding**（[S16]）：VLA 窄域微调后指令敏感性下降，需要反事实对比目标来保住 grounding。
- **Anchor-Align**（[S17]）：标准 BC 会覆盖 VLM 的 OOD 表征；加 representation anchoring 可在不增数据的情况下恢复 OOD 泛化。
- **GHOST**（[S9]）：层级 sub-goal（3D EE pose 分布）+ 低层 goal-conditioned controller，稳定优于 flat Diffusion Policy；说明「目标层 + 动作层」分解本身有增益。
- **ELASTIC**（[S11]）/ **DA-SIP**（[S12]）：测试时算力可沿并行/串行两轴分配；学出来的调度在匹配成功率下降低延迟 34%，或在匹配算力下 Pareto 占优。支持 ACA。
- **Adaptive Action Chunking**（[S13]）/ **Event-Triggered Async Inference**（[S14]）：chunk 长度/推理时机应按不确定性/场景变化自适应；事件触发异步在动态场景平均 95% 成功，比固定间隔基线高 55pp。支持 UGCC/ETR。
- **Recova**（[S20]）/ **Kintsugi-VLA**（[S20b]）：失败恢复可以被结构化学习；失败 rollout 可以转成 recovery data。支持 IIU-R 的训练方式。

### 2.4 与第 7 轮失败模型的关系

第 7 轮列了 P1–P6（目标槽位 grounding、接近碰撞、姿态不对、释放过早、插入不够、不验证）。本轮把它们压缩成三段：

| 第 7 轮 | 本轮归属 | 本轮组件 |
|---|---|---|
| P1 目标槽位/落点 grounding | 意图→目标 | RIC + SGG |
| P3 姿态不对 | 目标分布 | SGD（多峰 6D） |
| P2 接近碰撞 | 执行 | FAD + 碰撞打分 |
| P4 释放过早/过高 | 执行/验证 | 谓词校验 + 缓放 |
| P5 插入深度/力不够 | 执行/验证 | 插入 primitive + 谓词 |
| P6 不验证就以为完成 | 验证/恢复 | 谓词 + IIU-R |

这不是推翻，而是把「放置六类根因」映射到「意图/目标/执行/恢复」四层，便于分配模块。

### 3.2 RIC：评分细则→类型化意图程序

**输入**：32 个任务的 `score_steps`、`en_desc`、5 条复述、`generalization` 备注（[S5]）。
**输出**：每个任务一个 `IntentProgram`（JSON），推理时按 instruction 匹配。

**Schema**：

```json
{
  "task_id": "T06",
  "slug": "color_arrangement",
  "canonical": "Arrange the blocks from right to left in the order: red, green, yellow.",
  "paraphrases": ["...5 条..."],
  "phases": [
    {
      "phase": 1,
      "weight": 30,
      "action": "place",
      "object": {"category": "block", "color": "red", "ordinal": null},
      "target": {"type": "region", "relation": "rightmost", "axis": "left-right"},
      "constraints": ["upright"],
      "predicate": {"symbolic": "red_block.at(rightmost)", "visual": "red block on rightmost pad"},
      "tolerance": {"pos_m": 0.02, "rot_deg": 15}
    },
    {
      "phase": 2,
      "weight": 30,
      "action": "place",
      "object": {"category": "block", "color": "green"},
      "target": {"type": "region", "relation": "middle", "axis": "left-right"},
      "predicate": {"symbolic": "green_block.at(middle)"}
    },
    {
      "phase": 3,
      "weight": 40,
      "action": "place",
      "object": {"category": "block", "color": "yellow"},
      "target": {"type": "region", "relation": "leftmost", "axis": "left-right"},
      "predicate": {"symbolic": "yellow_block.at(leftmost)"}
    }
  ]
}
```

T27 的例子（颜色序 → 叠放序）：

```json
{
  "task_id": "T27",
  "canonical": "Stack the three bowls in the order: red, green, blue.",
  "phases": [
    {"phase": 1, "weight": 30, "action": "place",
     "object": {"category": "bowl", "color": "red"},
     "target": {"type": "region", "relation": "middle"},
     "predicate": "red_bowl.at(middle)"},
    {"phase": 2, "weight": 30, "action": "stack",
     "object": {"category": "bowl", "color": "green"},
     "target": {"type": "object", "ref": "red_bowl"},
     "predicate": "green_bowl.on(red_bowl)"},
    {"phase": 3, "weight": 40, "action": "stack",
     "object": {"category": "bowl", "color": "blue"},
     "target": {"type": "object", "ref": "green_bowl"},
     "predicate": "blue_bowl.on(green_bowl)"}
  ]
}
```

T10 的例子（序数 + 插入）：

```json
{
  "task_id": "T10",
  "canonical": "Position the power strip properly and plug the plug into the first socket.",
  "phases": [
    {"phase": 1, "weight": 30, "action": "grasp",
     "object": {"category": "power_strip"},
     "predicate": "gripper.holds(power_strip)"},
    {"phase": 2, "weight": 30, "action": "grasp",
     "object": {"category": "plug"},
     "predicate": "gripper.holds(plug)"},
    {"phase": 3, "weight": 40, "action": "insert",
     "object": {"category": "plug"},
     "target": {"type": "object", "ref": "power_strip", "part": "socket", "ordinal": 1},
     "predicate": "plug.inserted(socket_1)",
     "tolerance": {"pos_m": 0.005, "rot_deg": 5, "depth_m": 0.01}}
  ]
}
```

**编译流程**：

1. 离线用 LLM（GPT/Claude/Qwen 任一）按 schema 生成 32 个任务的程序；人工核对 32×5=160 条复述的匹配与 phase 顺序。
2. 对 T06/T27 这类「顺序 + 轴 + 颜色」的任务，显式写一个 `order_solver`：`order = [red, green, yellow]`，`axis = right-to-left`，`positions = [rightmost, middle, leftmost]`。不要指望 LLM 每次都对；把解析结果固化成 JSON，人工检查。
3. 对 T04/T24 这类「属性/类别匹配」的任务，写 `match_solver`：`target = argmax_{plate} color_similarity(fruit, plate)` 或 `category_map[food]`。
4. 对 T08 的「top book」，写 `superlative_solver`：`target = argmax_z(books)`。
5. 推理时：
   - 先做精确匹配（小写、去标点、去冠词）；
   - 再做句嵌入最近邻（阈值 τ）；
   - 都不中时，用轻量模板解析器（正则 + 颜色/序数/关系词表）生成临时程序；
   - 最后回退到该任务的 canonical 程序。
6. 程序不参与梯度；它是确定性代码 + JSON。这样既符合「单模型」的合规倾向，也方便审计。

**为什么不用端到端 VLM 直接出目标？** 因为端到端 VLM 在 OOD 场景里容易「视觉反应式」：它可能抓住最近的物体，而不是指令指定的物体（[S16][S17]）。类型化程序强制模型先解析「哪个物体、哪个目标、什么关系」，再交给几何/扩散去落地。这是把「语言理解」和「空间 grounding」解耦，降低 OOD 方差。

### 3.3 CAT：契约对齐训练

**目标**：让训练分布 = 推理 API 分布，避免特权键泄漏。

**API 观测集合**：

```python
O_API = {
  "observation.images.cam_left_high",
  "observation.images.cam_right_high",
  "observation.images.cam_left_wrist",
  "observation.images.cam_right_wrist",
  "observation.state.left_arm",
  "observation.state.right_arm",
  "observation.state.left_ee_pose_gripper_base",
  "observation.state.right_ee_pose_gripper_base",
  "observation.state.left_gripper",
  "observation.state.right_gripper",
  "observation.state.lower_body",
  "observation.language",
}
```

**训练协议**：

1. 加载官方 LeRobot 数据集；把 `head_stereo_left/right` 映射到 `cam_left_high/right_high`，`wrist_left/right` 映射到 `cam_left_wrist/right_wrist`。
2. **丢弃**所有不在 `O_API` 的键（torso、d435、leg、waist、recomputed_ee_valid）。
3. 动作头只训练 API 支持的动作键：
   - 若选 EE：`left_ee_pose_gripper_base` [6] + `right_ee_pose_gripper_base` [6] + `left_gripper` [1] + `right_gripper` [1] + `pivot` [7]；
   - 若选 joint：`left_arm` [7] + `right_arm` [7] + 同上。
   - 数据集里的 `action.lower_body` [15] 只用于推导 `pivot` [7]（如果映射关系明确）；否则只用 `action.pivot`。
4. 3D 输入：
   - 若 `cam_left_high/right_high` 可标定：用 OpenCV stereo SGBM 或 RAFT-Stereo 估深度；
   - 否则：用单目深度（Depth Anything 类）或直接用 2D 关键点 + EE 位姿做 2.5D；
   - 不要用 `state_d435` 作为深度/外参。
5. 数据增广：背景替换、颜色抖动、随机遮挡、随机干扰物、位置平移（若可回放）；这些增广模拟五轴，但不引入外部数据。
6. **API-simulated 验证集**：把 held-out 演示的观测裁剪成只剩 `O_API` 键，测 `Δ_contract = Succ_all_keys − Succ_API_keys`。若 `Δ_contract > 3pp`，说明模型在用特权键，必须重训/正则化。

**为什么这是创新点而不是普通工程？** 因为大多数参赛者会直接在完整数据集上训练，模型会隐式依赖 `state_torso`/`state_d435`/腿腰关节；这些键在 API 不存在。这个 train-test 契约差是一个**可测量、可修复、可能直接解释几个百分点**的隐藏坑。把它做成协议（mask + API-simulated 验证）而不是一次性检查，是「场景落地」的具体研究贡献。

### 3.4 SGG：场景图 + 关系求解 + 目标 overlay

**输入**：4 路 RGB、双目/单目深度、左右 EE 位姿、夹爪、language/IntentProgram。
**输出**：`GoalState`：

```python
GoalState = {
  "phase": int,
  "object_id": str,          # 当前要操作的物体
  "target_id": str | None,   # 目标容器/区域/物体
  "goal_pose_base": (p, R),  # 6D，base 系
  "relation": str,           # on/in/leftmost/middle/...
  "overlay": np.ndarray,     # 渲染到图像上的十字/朝向/容差圈
  "confidence": float,
  "predicate": dict,
}
```

**场景图构建**：

- 节点：物体（类别、颜色、2D mask、3D centroid、6D pose、affordance）、容器/区域（开口、内部、支撑面）、机器人（EE、夹爪）。
- 边：left-of/right-of/front-of/behind/on/in/near。
- 检测/分割：
  - 优先用**类别级几何 + 颜色分割**（HSV/Lab + 连通域 + 深度聚类），不依赖外部大模型；
  - 若需要开放词汇，用轻量检测头（在 33k 上用自动标签训练）或 VLM 的 attention 热图；
  - 避免在推理时引入 SAM/GroundingDINO 这类独立大模型，以免违反「单模型」精神。
- 3D：双目深度 → 点云 → 桌面平面 RANSAC → 物体 centroid/6D（PCA + 支撑面）；若单目，用 EE 位姿 + 像素射线 + 桌面平面求交，精度较低但可用。

**关系求解器**（确定性，按 IntentProgram 的 target.relation 调用）：

| 关系 | 求解 |
|---|---|
| `leftmost` / `rightmost` | 在桌面/base 系按 y（或 x，取决于机器人朝向）排序，取极值 |
| `middle` | 排序后取中位；若偶数个，取靠近目标区域的那个 |
| `top` | 按 z 取最大；若 z 相近，按图像 y 取最小 |
| `matching color` | 在候选容器中取与物体颜色直方图/嵌入最相似者 |
| `designated spot` | 用演示的目标位姿聚类 + 当前场景配准；或检测标记点（彩色圆点/胶带） |
| `ordinal` | 按任务定义的轴排序，取第 k 个；k 从 IntentProgram 来 |
| `on/in` | 目标容器/支撑面的 6D + 开口方向；用几何关系判断 |

**目标 overlay**：

- 把 `goal_pose_base` 投影到头相机/腕相机，画十字（位置）、短线段（朝向）、圆（容差）。
- 训练时用演示的真实目标位姿做**同一渲染管线**，保证 train/test overlay 同分布；否则模型会学「看渲染纹理」而不是「用目标」。
- overlay 是给 FAD 的条件，不是给人类的可视化；它把 3D 目标变成 2D 空间提示，降低 FAD 的 grounding 负担。

**置信度与回退**：

- `confidence = f(检测分数, 深度有效像素比例, 关系 margin, 与演示目标的一致性)`。
- 若 `confidence < τ_c`：
  - 回退 1：检索 K 条最相似演示的释放位姿，做容器系变换；
  - 回退 2：只用腕部相机做视觉伺服到目标区域；
  - 回退 3：把 phase 标记为「低置信」，ACA 增加 SGD 样本数或请求更多观测。

### 3.5 SGD：慢扩散目标分布

**训练数据**：

- 对每个任务 t、每个 place/insert/stack phase i，从演示中取**释放时刻**的 EE 位姿 `T_B^{G}`（base 系）和目标物体/容器位姿 `T_B^{R}`。
- 归一化到目标容器系：`H = (T_B^{R})^{-1} T_B^{G}`；训练时学 `H` 的分布，推理时用当前 `T̂_B^{R}` 还原 `T̂_B^{G} = T̂_B^{R} H`。这样对位置/背景/容器外观更鲁棒。
- 姿态表示：3D 位置 + 6D 旋转（旋转矩阵前两列，Gram-Schmidt 正交化）；共 9 维。
- 每个 phase 的样本量：该任务演示数 × 该 phase 出现次数；HangCup 1,043 条，其他任务约 1k，足够训练一个小扩散头。

**模型**：

- 条件 `c = [e_intent, e_phase, g_scene, h_goal]`：
  - `e_intent`：IntentProgram 的嵌入（任务/phase/object/target/relation）；
  - `e_phase`：phase index + 进度；
  - `g_scene`：场景图编码（目标物体/容器/支撑面的几何特征、相对位姿）；
  - `h_goal`：SGG 的粗目标热图/区域特征。
- 网络：1D/2D 条件 U-Net 或 MLP + FiLM；参数量 10–50M；输入 9 维 + 条件向量；输出噪声/速度。
- 训练：DDPM 或 flow matching；`L = E_{t,x0,ε} ||ε − ε_θ(x_t,t,c)||²`（或速度场）。
- 推理：M 个样本（M=8–32），按以下分数排序：

```text
s(x) = λ_c s_collision(x)      # 与场景/容器/其他物体的 signed distance
     + λ_r s_reach(x)          # IK 可达性 / 关节限位
     + λ_s s_stable(x)         # 支撑多边形 / 重心 / 容器内
     + λ_g s_goal(x)           # 与 SGG 粗目标/关系谓词的一致性
     + λ_p log p_θ(x|c)        # 扩散先验
```

- 取 `argmax s(x)` 作为 `goal_pose_base`；`u_goal` 用样本离散度：

```text
u_goal = (1/M) Σ_m ||p_m − p̄||² + λ_R (1/M) Σ_m ||log(R_m^T R̄)||²
```

- 若 `u_goal` 高：增加 M、降低执行速度、或回退到中位数/检索；若 `u_goal` 低：直接用 top-1。

**为什么是「慢」扩散**：它只在 phase 边界（抓取完成、移动到目标上方、释放前）跑，不在 30Hz 控制环里跑。一次 M=16、10 步的采样在 100–300ms 量级；180 秒预算足够。FAD 才是每步跑的「快」扩散。

**与第 7 轮 OPT 的关系**：OPT 是中位数 + 离散度阈值；SGD 是分布采样 + 打分。OPT 作为 SGD 的 fallback（当扩散头未训练好/延迟超预算/透明物体导致条件不可靠时）。这是升级，不是替换。

### 3.6 FAD：快扩散动作头

**输入**：当前 4 路 RGB（可堆叠历史）、proprio、SGG overlay、IntentProgram 嵌入、phase、IIU-R 的 intervention token。
**输出**：动作 chunk `a_{t:t+H}`，H = `action_chunk_size`；EE 空间：左右各 6D pose + 2 gripper + 7 pivot = 21 维/步（或 joint：7+7+2+7=23）。

**训练**：

- 基座：WALL-OSS-0.5 4B（flow matching + 离散 token；Apache-2.0，[S7]）或 MolmoAct2（7B，spatial reasoning；Apache-2.0，[S6]）。推荐 WALL-OSS 作为部署基座（4B、flow matching、跨 embodiment），MolmoAct2 作为可选的 spatial teacher。
- 冻结 VLM backbone，训练 LoRA + action expert（flow matching）；或全量微调 action expert。
- 损失：

```text
L_FAD = E_{t,a0,a1,c} ||v_φ(a_t,t,c) − (a_1 − a_0)||²
a_t = (1−t)a_0 + t a_1,  a_0 ~ N(0,I),  a_1 = demo action chunk
```

- 辅助损失：
  - `L_goal`：预测当前 chunk 结束时是否到达 goal（BCE）；
  - `L_phase`：phase 分类/进度（CE）；
  - `L_smooth`：jerk 惩罚（||a_{k+1}−2a_k+a_{k−1}||²），减少抖动；
  - `L_overlay`：goal overlay 与动作终点的一致性（可选）。
- 训练时注入 overlay：用演示的真实目标位姿渲染 overlay；随机扰动 overlay（±2cm/±10°）做鲁棒性；避免模型只认完美 overlay。
- 蒸馏：把 10–20 步 flow matching 蒸到 4–8 步（consistency/rectified flow）；目标 `get_action` p99 <100ms（单卡、单端口）。若达不到，降分辨率/降步数/换更小 action expert。

**动作空间选择**：

- EE：与 SGD 的 6D 目标直接对齐；适合放置/插入；避免 IK 误差进入动作标签。
- Joint：可能更平滑、更适合接触丰富任务；但需要 IK 把 SGD 目标转成关节目标，且 API 的 joint 动作是绝对目标，误差会累积。
- 建议：主选 EE；用调试槽在 T10（插入）和 T19（拉链）做 EE vs joint A/B；如果 joint 明显更好，再切换（但只能全局切换）。

### 3.7 UGCC：固定 chunk 内的不确定性门控

**问题**：API 的 `action_chunk_size` 固定，不能每次返回不同长度；但我们需要「高不确定时更反应」。**解法**：固定长度 H，改变 chunk 的**内容**。

**推理逻辑**：

```python
def get_action(obs):
    # 1) 更新场景图/相位/时间
    sg = sgg.update(obs)
    phase = ric.current_phase(obs, sg)
    t_left = 180.0 - elapsed()

    # 2) 相位边界：跑慢扩散
    if phase.changed or sg.low_confidence:
        goal, u_goal = sgd.sample(sg, phase, M=aca.m(phase, t_left))
    else:
        goal, u_goal = self.last_goal, self.last_u_goal

    # 3) 快扩散：采样 N 个 chunk
    chunks = fad.sample(obs, goal, phase, N=aca.n(phase, t_left))
    u_action = agreement(chunks)

    # 4) 场景变化/干扰检测
    u_scene, intervention = detect_change(obs, self.prev_obs, sg)

    # 5) 固定 H 的内容门控
    plan = chunks[0]
    if intervention:
        mode = iiu.classify(sg.delta, obs)
        plan = iiu.recover(mode, plan, goal, phase)   # resume/reground/redo/regrasp/wait
        H_exec = min(4, H)
    elif u_scene > τ_s or u_goal > τ_g or phase.risk > τ_r:
        H_exec = min(8, H)
    elif u_action > τ_a:
        H_exec = min(12, H)
    else:
        H_exec = H

    # 6) 后半段填保守动作（保持/刹车），下一次调用重规划
    out = plan[:H_exec]
    if H_exec < H:
        out = concat(out, hold_or_brake(obs, H - H_exec))

    # 7) 与上一 chunk 尾部融合，避免 jerk
    out = blend(self.prev_tail, out, k=3)

    self.prev_tail = out[-3:]
    self.prev_obs = obs
    return out
```

**关键点**：

- `u_action`：N 个 chunk 的终点/轨迹方差；`u_scene`：当前帧与上一帧/预测帧的视觉变化（可用简单帧差 + EE 区域加权，或学习一个视觉动力学 monitor）；`u_goal`：SGD 样本离散度；`phase.risk`：来自 RIC 的相位风险（插入/闭合/叠放 = 高；自由空间移动 = 低）。
- 「保持/刹车」不是零动作，而是保持当前 EE 位姿 + 夹爪状态，或沿当前速度减速到零；避免突然停住造成 jerk。
- 融合：新 chunk 的前 k 个动作与上一 chunk 的后 k 个动作做线性/余弦加权，减少 chunk 边界跳变；这也是 ACT 的 temporal ensembling 思路。
- 这套逻辑完全在固定 `action_chunk_size` 契约内；不违反 API。

### 3.8 IIU-R：干扰意图理解 + 恢复

**干扰原语**（从官方 human_1/human_4 备注归纳，[S5]）：

| 原语 | 官方备注例子 | 场景变化 | 恢复模式 |
|---|---|---|---|
| `TRANSLATE` | T27 粉色碗向下；T19 包向左；T21 盘子向前 | 目标物体/容器平移 | 重新 grounding 目标 → 继续当前 phase |
| `UNDO` | T27 叠了第二个后拿下；T19 拉上后拉开；T14 拧开后拧回 | 上一步被撤销 | 重做被撤销的 phase |
| `REMOVE` | T12 中途把锁拿走 | 目标消失 | 等待/重规划；若不可恢复则优雅失败 |
| `OCCLUDE` | 人手/物体挡住相机 | 视觉遮挡 | 等待/切换视角/用腕相机 |
| `DISTRACT` | T24 可乐/薯片快到了又放回起点 | 运动目标被移走 | 跟踪/重新瞄准/等待下一周期 |
| `REVERSE` | T17 笔盒合上后手动打开；T19 拉开拉链 | 关节/闭合被反向 | 重做闭合 phase |

**检测**：

- 场景图 delta：`ΔG_t = G_t − Ĝ_t`，其中 `Ĝ_t` 是「机器人动作导致的预期场景图」（用 FAD 的动作 + 简单前向模型/上一次观测预测）。
- 若 `ΔG_t` 中有物体位姿跳变 > τ（且不是机器人造成的），标记为 intervention。
- 人手检测：肤色/手部检测器（轻量）或视觉变化区域 + 深度突变；只作为辅助信号，不依赖。
- 分类头：`q_ψ(primitive | visual features, ΔG_t, phase)`；轻量 MLP/Transformer head，接在 backbone 的视觉特征上；输出 6 类 + confidence。

**恢复**：

- `TRANSLATE`：重跑 SGG（用新位置），更新 goal；FAD 条件加 `intervention_token=TRANSLATE`；继续当前 phase。
- `UNDO`：phase 回退到被撤销的 phase；重跑 SGD/FAD；`intervention_token=UNDO`。
- `REMOVE`：如果目标不可达，等待 1–2 秒看人类是否放回；否则重规划到剩余可完成步骤；若成功谓词不可能满足，标记失败但保留步骤分。
- `OCCLUDE`：切换到另一路相机/腕相机；等待遮挡消失；不要盲目执行。
- `DISTRACT`：重新检测运动目标；如果传送带周期性，等待下一件；否则跟踪。
- `REVERSE`：重做闭合/关节操作；`intervention_token=REVERSE`。

**训练数据**：

- 用官方备注 + 2.5D 编辑合成：平移目标物体/容器；移除物体（inpaint）；遮挡（贴手/物体 mask）；反向关节（如果可重放）；传送带目标位移。
- 每类 200–500 个合成 episode；与真实演示混合，加权采样。
- 分类头用合成标签训练；在调试槽用真实干扰做小样本校准。
- 如果没有仿真/外部数据，2.5D 编辑只用官方图像 + 几何变换；这是合规的「对官方数据的增广」，不是外部数据。

**与第 7 轮 NRB 的关系**：NRB 是训练时的「破坏→恢复」数据；IIU-R 是推理时的「检测→分类→恢复」。NRB 的数据可以复用，但 IIU-R 多了推理时的意图分类和恢复模式选择。这是升级。

### 3.9 ACA：剩余 180 秒的算力分配

**形式化**：

- 任务有 K 个 phase；每个 phase i 选择算力等级 `c_i`（例如 M ∈ {4,8,16,32}，N ∈ {1,2,4,8}，步数 ∈ {4,8,16}）。
- 延迟 `ℓ_i(c_i)` 由离线 profile 测得；成功率 `p_i(c_i)` 由离线校准/调试槽估计。
- 预算 `B = 180 − elapsed − safety_margin`（safety_margin 10–20s，给通信/重置/异常）。
- 目标：

```text
max_{c_1..c_K} Σ_i log p_i(c_i)
s.t. Σ_i ℓ_i(c_i) ≤ B
```

- 用 DP 在离散预算上求解（K ≤ 5，预算粒度 1s，状态很小）。
- 运行时用观测到的不确定性更新 `p_i`：

```text
p_i(c_i) ← σ(α_i + β_i u_i + γ_i c_i)
```

其中 `u_i` 是当前 phase 的 `u_goal/u_action/u_scene` 组合；`α,β,γ` 从离线校准拟合。

**实际策略（简化版，先跑起来）**：

```text
if phase.risk == HIGH and t_left > 30s:
    M = 16, N = 4, steps = 10
elif phase.risk == HIGH and t_left <= 30s:
    M = 4,  N = 1, steps = 6   # 或直接 primitive
elif phase.risk == LOW and t_left > 20s:
    M = 4,  N = 1, steps = 4
else:
    M = 2,  N = 1, steps = 4
```

**低算力回退**：

- 插入/闭合类：用确定性 visual servo + 柔顺控制 primitive（如果有）；否则用 SGD 中位数 + 短 chunk。
- 自由空间移动：用 FAD 单样本 + 长 chunk。
- 时间极紧：跳过 SGD，直接用上一次 goal + FAD 单样本；保证在 180s 内完成或至少拿到步骤分。

**为什么这是「场景落地」而不是普通工程**：它把 180 秒从「外部约束」变成「策略的一部分」；算力分配的依据是评分细则的相位风险和扩散模型自身的不确定性，而不是固定的每步采样数。这是可以在调试槽里测量、在离线校准、在代码里审计的。

### 3.10 ETR：事件触发运行时

**服务拓扑**：

- N 个端口，每端口一个 `PolicyService`；如果显存允许，每端口一个模型副本（最稳）；否则共享一个推理后端 + 每端口轻量 endpoint + 请求队列。
- 每端口独立 `reset()` 状态：IntentProgram、phase、scene graph、prev_obs、prev_tail、time budget、IIU 状态。
- 异步：
  - 感知线程：更新场景图/深度；
  - 慢扩散线程：相位边界触发，缓存结果；
  - 快扩散线程：每 `get_action` 触发；
  - 主线程：组装 chunk、校验、返回。
- 延迟守卫：p99 超过阈值（例如 150ms）时，降 N/降步数/降分辨率；记录告警。
- 健康检查：每端口心跳；模型副本失败时切换到备用副本（如果有）。
- 动作融合：chunk 边界 temporal ensembling；gripper 动作做 debounce，避免抖动。
- 统计：每 episode 记录 phase 成功、延迟、u_goal/u_action/u_scene、干预类型、恢复结果；用于离线诊断和 ACA 校准。

**事件触发重规划**：

- 触发条件：`u_scene > τ_s`、谓词从 true→false、IIU 检测到 intervention、`u_goal > τ_g`、phase 完成、时间不足。
- 重规划动作：截断当前 chunk 的剩余部分（用保持/刹车填充）、重跑 SGG/SGD、更新 FAD 条件。
- 注意：不能改变 `action_chunk_size`；只能改变内容。

## 4. 数据引擎

### 4.1 相位切分与目标位姿库

1. **相位定义**：直接来自 RIC 的 `phases`（score_steps 的顺序）。
2. **边界检测**：
   - 抓取 phase：夹爪闭合事件（`action.left/right_gripper` 或 `observation.state.*_gripper` 从开到闭）；
   - 放置 phase：夹爪打开事件 + 物体相对目标容器稳定；
   - 插入 phase：EE 接近目标 + 夹爪保持闭合 + 物体/插座相对位姿稳定；
   - 闭合/拉链/倒药：关节/物体状态变化 + 末端轨迹终点。
3. **人工抽检**：32 任务 × 每任务 3–5 条，检查相位边界；错误率 >10% 的任务重标。
4. **目标位姿库**：
   - 每个 phase 的释放时刻 `t_rel`：夹爪打开/物体脱离的帧；
   - `T_B^G(t_rel)`：EE 位姿（base 系，数据集直接有）；
   - `T_B^R`：目标容器/区域位姿（用检测/标注/演示终点估计）；
   - `H = (T_B^R)^{-1} T_B^G(t_rel)`；
   - 每任务每 phase 存 `{H_i}`、`τ_task`（95 分位差）、场景元数据。
5. **质量门槛**：抽检 10%，位姿误差 <1cm 才入库；透明/小物体任务单独分桶。

### 4.2 合成干扰（IIU-R 数据）

| 原语 | 合成方法 | 规模 |
|---|---|---|
| TRANSLATE | 2.5D 编辑：分割目标物体/容器，平移 2–10cm；更新 3D 位姿 | 6 任务 × 300 |
| UNDO | 反向重放上一步 / 图像编辑展示撤销状态 | 8 任务 × 200 |
| REMOVE | 分割 + inpaint；从场景图删除 | 4 任务 × 200 |
| OCCLUDE | 人手/物体 mask 叠加；随机位置/时长 | 8 任务 × 200 |
| DISTRACT | 传送带目标沿运动方向平移/回退 | T24 × 300 |
| REVERSE | 关节/拉链/盒盖反向；用演示反向或脚本 primitive | 6 任务 × 200 |

总计约 6–8k 合成 episode；相对 33k 真实数据约 20–25%，不主导训练。所有合成都基于官方图像/几何，不引入外部数据。

### 4.3 意图对比数据（ICP）

- 正样本：同一任务的 5 条复述（[S4]）。
- 负样本：属性/关系反事实：
  - 颜色替换：red ↔ green ↔ yellow ↔ blue；
  - 序数替换：fruit 1/2/3、bowl 1/2/3、socket 1/2；
  - 关系替换：leftmost ↔ middle ↔ rightmost；top ↔ bottom；
  - 目标替换：plate ↔ basket ↔ shelf。
- 规模：32 任务 × 5 正 × 8 负 ≈ 1,280 对；可在线生成，无需人工标注。
- 损失：InfoNCE 或 triplet；作用在 language encoder / intent embedding 上；推理时不需要负样本。

### 4.4 OOD 离线验证集

| 轴 | 构造 | 指标 |
|---|---|---|
| 位置 | 平移物体初始位姿/目标区域（若可回放）；或图像空间平移 + 3D 一致变换 | grounding accuracy, goal pose error |
| 背景 | 替换桌布纹理/颜色（用其他任务背景或纯色） | 目标选择准确率 |
| 干扰物 | 插入随机物体（从其他任务裁剪） | 目标选择准确率、碰撞率 |
| 未见物品 | 颜色/形状/材质替换（图像编辑或同类不同实例） | 类别级 grounding、抓取点 |
| 人为干扰 | 官方备注 + 合成原语 | 恢复率、phase 成功率 |

注意：离线指标是代理，不是真机成功率；真机只能用调试槽/计分跑验证。

## 5. 训练配方

### 5.1 基座选择

| 基座 | 优势 | 劣势 | 建议 |
|---|---|---|---|
| WALL-OSS-0.5 4B（[S7]） | 4B、flow matching、20+ embodiment、Apache-2.0、部署友好 | 无显式空间 pointing；需要加 SGG/overlay | **主基座** |
| MolmoAct2 7B（[S6]） | 显式 spatial reasoning、pointing/depth token、强 grounding | 7B、180–790ms、开环 batch、G1 需额外训练 | 可选 teacher / 备选 |
| DreamZero 14B（[S8]） | 世界模型、零样本物理泛化、7Hz 闭环 | 14B、部署成本高、7Hz | 离线教师/反事实生成，不进主推理 |
| WLA-1.0-Base 6B（第 7 轮） | Unitree 自家、Apache-2.0、24GB 可微调 | 生态较新 | 备选/对照 |

**推荐**：WALL-OSS-0.5 4B + LoRA + 新 action expert 头；SGG/overlay 作为额外输入；SGD 作为独立小头（10–50M）。如果调试槽显示 MolmoAct2 的 spatial token 明显更强，再考虑蒸馏到 WALL-OSS（pointing/depth 辅助损失），而不是直接部署 7B。

### 5.2 训练阶段

| 阶段 | 数据 | 目标 | 退出条件 |
|---|---|---|---|
| 0 | 官方 33k，CAT mask | 复现 WALL-OSS 基线 | held-out 不降 |
| 1 | + RIC 相位标签 | phase 分类/进度 | phase F1 > 0.8 |
| 2 | + SGG overlay | 学会用 overlay | 离线 goal 跟随误差下降 |
| 3 | + SGD 目标库 | 目标扩散采样 | 释放位姿 τ 内 ≥80% |
| 4 | + ICP 对比 | 意图敏感性 | 反事实指令目标变化正确率 >70% |
| 5 | + IIU-R 合成 | 干扰分类/恢复 | 分类 F1 > 0.7；恢复成功率 >50% |
| 6 | + UGCC/ACA 规则 | 延迟/反应性 | p99 <150ms；human 轴恢复提升 |
| 7 | 蒸馏/量化 | 部署 | p99 <100ms；动作平滑 |

### 5.3 超参（起始值）

- Backbone：WALL-OSS-0.5 4B；LoRA rank 64 / alpha 128；action expert 全量或 LoRA。
- 优化器：AdamW；lr 1e-4（LoRA）/2e-5（全量）；cosine；warmup 3%；global batch 64–128；bf16。
- Action chunk：H=16；horizon 0.5–1s；flow matching 训练步数 10–20；推理蒸馏到 4–8 步。
- SGD：9D pose；M=8–32；DDPM 1000 训练步 / 推理 10–20 步；条件 FiLM；小 U-Net/MLP。
- 损失权重：`L_FAD + 0.1 L_goal + 0.2 L_phase + 0.05 L_smooth + 0.1 L_ICP`。
- 数据混合：真实 100% → +合成 20–25%；合成用 GF 软权重，避免负迁移。

### 5.4 算力

- 阶段 0–2：8×H100，1–2 周（4B LoRA + action head）。
- SGD/ICP/IIU-R：8×H100，3–5 天。
- 阶段 3–6：8×H100，2–3 周。
- 推理：1×H100/A100 80GB 可跑 4B + 小 diffusion 头；24GB 需量化/LoRA/降分辨率。
- N 端口：如果 N=3，单卡共享后端 + 请求队列；或 3×24GB 副本。按实际 N 调整。

### 6.5 统计功效

- 320 次运行，p=0.3：SE=√(0.3×0.7/320)=0.0256 ≈ 2.56pp。

- 轴级只有 2 次/任务（64 次/轴），SE≈5.7pp；不要用轴级小差异下结论。

## 7. 创新点清单（持续迭代；动机/差异/可行性/资源/步骤/风险/状态）

> 状态：押注=本轮主线；保留=沿用；升级=旧点被改造；降级=保留但非主回路；砍=不做。

### I1 RIC 评分细则→类型化意图程序（升级 SSG｜押注）
- **动机**：官方 score_steps + 5 复述是公开的意图规格；T06/T27 的组合指代（顺序+轴+颜色）和 T10 的序数插入，flat language embedding 容易绑错。
- **差异**：第 7 轮 SSG 是「状态机」；RIC 是「可 grounding 的类型化程序」，含 object/target/relation/constraint/predicate/tolerance。推理不跑 LLM，确定性匹配。
- **可行性**：32×5=160 条，离线 LLM 编译 + 人工核对 1 人周；JSON 匹配 <1ms。
- **资源**：无额外数据；CPU；1 人周。
- **步骤**：抽 32 任务 score_steps → LLM 生成 schema → 人工核对 → 写 order/match/superlative solver → 接 SGG/FAD。
- **风险**：LLM 解析错 → 人工核对；未见复述 → 嵌入/模板兜底；任务描述歧义 → 以 score_steps 为准。
- **状态**：押注。

### I2 CAT 契约对齐训练（新增｜押注）
- **动机**：数据集有 torso/d435/leg/waist，API 没有；训练隐式用特权键会导致推理分布外。API 只有 RGB，没有深度。
- **差异**：大多数队伍直接在完整数据集上训；CAT 把「只喂 API 键 + base 系 + 双目/单目深度 + API-simulated 验证」做成协议。
- **可行性**：纯数据管线；1 人周；可用现有 LeRobot 加载器。
- **资源**：无额外数据；CPU/GPU 数据加载。
- **步骤**：定义 O_API → mask → 相机映射 → 动作键映射 → 深度管线 → API-simulated held-out → 测 Δ_contract。
- **风险**：双目未标定 → 单目深度/2.5D 回退；相机物理不同 → 增广/调试槽校准；动作 pivot 映射不明 → 只用 action.pivot。
- **状态**：押注（低成本高回报）。

### I3 SGG 场景图 + 关系求解 + overlay（升级 PGL｜押注）
- **动机**：Spa-Bench 证明 OOD 空间 grounding 是主瓶颈；T06/T08/T24 需要关系/最高级/类别求解。
- **差异**：第 7 轮 PGL 是「槽位→锚点→位姿」三级；SGG 把「场景图 + 关系求解 + 置信度 + overlay」做成可解释管线，且不依赖外部大模型。
- **可行性**：颜色/深度/几何 + 轻量头；离线可验证；推理 <50ms。
- **资源**：无额外数据；1–2 人周；调试槽校准。
- **步骤**：场景图 schema → 检测/分割 → 3D 位姿 → 关系 solver → overlay 渲染 → 置信度/回退。
- **风险**：透明/小物体检测失败 → 腕相机/检索回退；双目未标定 → 2.5D；overlay 域差 → 训练/推理同渲染。
- **状态**：押注。

### I4 SGD 慢扩散目标分布（升级 OPT｜押注）
- **动机**：放置/插入是终局闸门；中位数会平均掉多峰；33k 演示的释放位姿是现成监督。
- **差异**：OPT 是 K 条中位数 + 离散度阈值；SGD 是条件扩散采样 M 个 6D 位姿 + 碰撞/可达/稳定/谓词打分 + 不确定度。扩散在「目标层」而不是「动作层」。
- **可行性**：小扩散头 10–50M；33k 数据足够；推理 100–300ms（相位边界）。
- **资源**：8×H100 3–5 天建库/训练；1 人月。
- **步骤**：相位切分 → 释放位姿库 → 容器系归一化 → 训练扩散 → 采样/打分 → 接 FAD。
- **风险**：透明/布料目标位姿估计失败 → 分桶回退 OPT/检索；延迟超预算 → 降 M/步数/蒸；多峰打分权重难调 → 调试槽校准。
- **状态**：押注。

### I5 FAD 快扩散动作 + UGCC 固定 chunk 门控（新增/升级｜押注）
- **动机**：API 固定 `action_chunk_size`；MolmoAct2 开环 10–30 步是自认弱点；human 轴需要中途反应。
- **差异**：不是变 chunk 长度（API 不允许），而是变 chunk 内容：高不确定时后半段保持/刹车，下一次重规划；用扩散样本一致性 + 场景变化 + 相位风险门控；chunk 边界时间集成。
- **可行性**：WALL-OSS flow matching 已有；UGCC 是推理逻辑；无需重训即可先跑。
- **资源**：1 人月工程 + 调试槽；GPU 推理。
- **步骤**：固定 H → N 样本一致性 → 场景变化检测 → 门控规则 → 保持/刹车动作 → 融合 → 延迟/jerk 测试。
- **风险**：门控误判 → 双阈值/调试槽校准；保持动作造成停滞 → 时间守卫；动作规律性 → 确定性采样/融合。
- **状态**：押注。

### I6 IIU-R 干扰意图理解 + 恢复（升级 NRB｜押注 human 轴）
- **动机**：官方 human 备注是逐任务剧本（平移/撤销/拿走/遮挡/运动目标）；MolmoAct2 开环正好被打。
- **差异**：NRB 是训练时回放；IIU-R 是推理时「检测异常→分类 6 原语→选择 resume/reground/redo/regrasp/wait」；分类头接 backbone。
- **可行性**：备注可 2.5D 合成；分类头轻量；恢复复用 FAD/SGD。
- **资源**：6–8k 合成 episode；1 人月；调试槽校准。
- **步骤**：备注→原语表→合成→分类头→恢复策略→intervention token→调试槽。
- **风险**：真实干扰与备注不同 → 通用异常检测 + 置信度回退；REMOVE 不可恢复 → 优雅失败/保步骤分；合成域差 → 真实小样本校准。
- **状态**：押注（human 轴）。

### I7 ACA 剩余 180s 算力分配（新增｜落地）
- **动机**：180s 是硬约束；固定每步采样浪费算力；ELASTIC/DA-SIP 证明自适应分配有效。
- **差异**：分配信号 = 评分细则相位风险 × 扩散不确定度 × 剩余时间；DP/规则，可审计；不是通用难度分类器。
- **可行性**：离线 profile + 校准表；K≤5，DP 很小；推理开销可忽略。
- **资源**：1 人周；调试槽数据。
- **步骤**：定义算力等级 → profile 延迟 → 校准 p_i(c_i) → DP/规则 → 运行时更新 → 回退 primitive。
- **风险**：校准不准 → 保守预算/安全边际；延迟抖动 → p99 守卫；过度分配 → 时间超限。
- **状态**：落地（主线辅助）。

### I8 ICP 意图对比训练（新增｜训练）
- **动机**：VLA 窄域微调后指令敏感性下降（[S16]）；5 复述 + 反事实可低成本造正负样本。
- **差异**：不改推理结构；只在 language encoder/intent embedding 上加 InfoNCE/triplet；负样本是属性/关系反事实。
- **可行性**：32×5×8≈1,280 对；在线生成；1 人周。
- **资源**：无额外数据；训练 GPU。
- **步骤**：反事实生成器 → 正负对 → 损失 → 与 FAD 联合训练 → 反事实测试。
- **风险**：负样本太简单 → 难负样本挖掘；过拟合模板 → 保留原始语言损失；与 FAD 冲突 → 小权重。
- **状态**：训练（可选，先离线验证）。

### I9 ETR 事件触发运行时（新增｜落地）
- **动机**：N 端口、状态隔离、延迟/动作规律性被记录；开环 chunk 需要中途重规划。
- **差异**：把「契约」变成运行时策略：固定 metadata、异步慢/快扩散、p99 守卫、动作融合、健康检查、per-port 状态。
- **可行性**：纯工程；1–2 人月；本地 stub 可测。
- **资源**：N 端口部署；监控。
- **步骤**：服务拓扑 → 状态隔离 → 异步 → 事件触发 → 融合 → soak。
- **风险**：并发延迟方差 → 独立副本/队列；端口不匹配 → 严格 N；模型副本显存 → 共享后端。
- **状态**：落地（必需）。

### I10 TPD 任务组合诊断（新增｜策略）
- **动机**：排名是 32 任务宏平均；「填谷」比「抛光」更划算；轴级只有 2 次/任务，需诊断而非排名。
- **差异**：把「任务 × 轴 × phase」做成热力图，按边际收益/成本分配数据/训练/调试槽。
- **可行性**：离线日志 + 调试槽；1 人周。
- **资源**：调试槽数据；分析脚本。
- **步骤**：定义矩阵 → 采集 → 估计 p_t/phase → 边际收益 → 分配。
- **风险**：样本少 → 贝叶斯平滑/置信区间；过拟合预览数据 → 只用真实调试槽。
- **状态**：策略（辅助）。

### I11 DebugLoop 平台调试回路（保留）
- 不计分单任务调试槽作发布门；每个大版本最多 1 槽；首选 T10/T27/T19；判定标准：终局 +≥10pp 且无回归。
- 风险：槽位稀缺/规则变化 → 离线代理 + 保守提交。

### I12 ICR 检索条件化（降级）
- 从主路径降为「目标图像/位姿检索 fallback」；用于 SGG 低置信、透明物体、慢扩散延迟超预算。
- 不再作为主策略的条件化机制；检索库是数据，不是模型。

### I13 L2L 产学研数据（降级/可选）
- 背景/位置轴的多样性仍有价值，但外部数据政策未核实；默认 OFF；只做协议/法务准备。
- 如果确认允许，按第 7 轮协议采集；否则赛后研究。

### I14 WLA-1.0-Base / GPR-VLA（保留）
- 唯一学习 backbone 的备选；如果 WALL-OSS 微调不顺，回退 WLA；GPR 的目标残差/可逆信念仍可用于 phase/predicate。

### I15 TLE/ACP/GF（保留，修剪）
- TLE 只做相位切分 + 目标位姿 + 谓词；ACP 只做位置/背景/干扰物/人为干扰的 2.5D 增广；GF 软权重防合成负迁移。

### I16 FLEET 工程检查单（保留为检查单）
- N 端口、状态隔离、RTC 式延迟弹性、健康检查；不再作为「第六轴」研究贡献。

### 已砍清单（跨轮）
- 全 32 任务高保真孪生；自由仿真数据；运行时仿真/MPC；仿真 RL；布料/拉链/透明全物理；WMA-0 进主路径；每任务 LoRA/模型合并；「步骤分占 60%」主论证；「终局权重 39.8%」主论证。
