# 第 47 轮（承接第 46 轮产物 v23；本轮灵感：创新点 × 轮足机器人） · Gait-Cert：把「底盘运动」升为一等公民的轮足步态-感知-姿态联合证书（架构 v11）

> 承接第 46 轮产物 v23（Memory-Safety-Voice）。v23 把记忆检索、语音指令、安全绑定叠加到 v10 能量-上下文-深度框架上，但所有版本共享一条从未写进定义的隐含假设 **H5：底盘准静态、运动学与感知/操作解耦**——能量租约只计感知功耗，姿态证书只由感知质量决定，安全绑定默认机器人「站在原地」。轮足机器人（wheel-legged）直接击穿 H5：同一平台上存在离散运动模式 g∈{轮式 W、足式 L、过渡 T}，每种模式的功耗、振动谱、轮滑/足底冲击、里程计漂移都不同；而底盘位姿是操作链的根，于是模式切换会在姿态证书上产生阶跃式扰动。若不在证书里显式建模，先前的 soundness 会在一次 W→L 切换中静默失效。另一个灵感词「创新点」提示的是方法层问题：**新形态的价值不是再叠一个模块，而是用新形态去证伪旧假设**。本轮据此提出「假设压力创新算子」，得到 v11 的 Gait-Cert：让步态模式成为能量租约、感知调度、姿态证书、安全绑定共享的同一个变量。

## 0. 直觉与动机

**灵感 1（轮足机器人 → 运动模式是新的根不确定性）**
直觉：轮式在平地高效，却怕打滑与高频振动；足式能越障，却功耗高、足底冲击会瞬态破坏位姿。最危险的瞬间是模式切换：两套里程计/动力学模型在交接，底盘位姿可能在几十毫秒内跳变。感知再好，若底盘在抖，机械臂末端一样会偏。因此姿态证书必须把「底盘此刻处于哪种运动模式、模式是否正在切换」作为签发条件，而不是背景噪声。

**灵感 2（创新点 → 假设压力测试，而非模块堆叠）**
直觉：过去每轮习惯把新灵感词做成又一个模块，容易变成同义反复的模块堆积。真正可辩护的创新点是：找到一个此前被默认、但新形态必然违反的假设，再把它变成一条可检验的证书义务。H5 就是本轮目标——「底盘准静态且与感知解耦」。把 H5 的否定写成约束，就自然长出跨层的耦合项，而不是外挂功能。

**灵感 3（耦合 → 步态与感知必须联合决策）**
直觉：选轮式还是足式，不只是「移动模块」的事。它同时决定耗电 P_g、姿态漂移 drift_g、振动对相机的破坏 Φ_g、以及该地形上的可观测性。因此步态 g 与感知模态 m 必须联合求解，并在模式切换处设置「交接守卫」；否则单方面优化移动或单方面优化感知都会把风险推给对方。

**耦合升级**：五层 v11 = 根信任（能量租约 + 步态租约 + 位姿连续性联合租约）+ L1 几何（步态条件化半径 r|g）+ L2 上下文（步态/地形先验）+ L3 安全（切换交接守卫与末端冻结）+ L4 采集（轮滑/足底冲击/振动谱数据）。

## 1. 形式化定义（增量：定义 59–64）

**定义 59（步态模式自动机）**
运动模式集合 g_t∈G={W, L, T_WL, T_LW}，转移 δ:G×A→G，a 为移动动作。每个模式携带四元组 (P_g, Φ_g(f), drift_g, c_g)：功耗、IMU 扰动功率谱、里程计漂移上界、可通行代价。T 模式表示切换中，禁止签发满宽姿态证书。

**定义 60（步态条件化姿态证书）**
证书 P_t(g) 的半径为
rad(P_t|g)=rad_perc(m_t) + L_v·‖v_t‖·Δt + drift_g·Δt + J_impact(g)·𝟙[foot strike] + J_slip·slip_t。
签发前提：g 在 [t, t+τ_p] 内保持且无未守卫切换。切换时必须重签；处于 T 模式时使用膨胀半径或冻结末端。

**定义 61（步态-感知联合能量租约）**
ℓ_{e,g}=(B_t, P_m+P_g+P_aux, τ_e, B_min)，剩余能量上界
E(t)=B_t − ∫_{τ_e}^{t}(P_m+P_g+P_aux)dτ − λ_b(t−τ_e)²。
能量可行判据：E(t)≥E_min(φ) 且 B_t≥B_min。任一租约过期→依赖它的姿态证书级联失效（与 v10 的 fail-closed 一致）。

**定义 62（联合步态-感知决策）**
(g*,m*)=argmax_{g∈G,m∈M} [Δtask(g,m)+Δcert(g,m)] / [P_g+P_m + c_slip·Risk_slip(g) + c_imp·Risk_imp(g)]
s.t. rad(P_t|g,m)≤rad_max，E(t+Δ|g,m)≥E_min，且 Guard(g_t→g) 可行。

**定义 63（切换交接守卫）**
切换 g→g′ 在时刻 τ 可行，当且仅当名义交接盒非空
P_τ(g) ∩ inflate(P_τ(g′), drift_{g′}·δ + slip_margin) ≠ ∅
且安全绑定 B(v_t,P_τ)≥θ_safe。否则冻结末端到当前安全盒，进入 Q_safe，并在切换窗口内禁止执行操作类指令。

**定义 64（假设压力创新算子）**
给定新平台 P_new 与现有证书集合 C_old，创新点集合
I={(H, C_H) | H∈Assumptions(C_old), P_new⊭H, C_H=由 ¬H 导出的跨层约束}。
本轮 H5 → C_{H5}={步态条件化半径, 切换交接守卫, 步态能量项}，并据此派生 IP-69/70/71。

## 2. 三大新增产出与既有 IP 升级

**IP-69 GRC（Gait-Regime Certificate）**
- 步态自动机与切换检测：W/L/T 的在线判别，切换检测延迟预算 ≤20ms
- 步态条件化半径：为 (g,m) 组合单独共形校准，T 模式单独膨胀核
- 切换交接守卫：位姿盒交接非空检验 + 失败即冻结末端

**IP-70 LSU（Locomotion Scheduler Unit）**
- 步态与感知模态联合效用求解，输出 (g*,m*) 与预热/切换计划
- 地形段预测：由上下文 c_t 预测未来模式可行性与功耗
- 防抖：切换滞回与最小驻留时间，抑制 W↔L 抖动

**IP-71 VIB-SLIP Adapter**
- 轮滑估计：轮速 vs IMU/足式里程计融合速度之差
- 振动谱：IMU/Welch 估计 Φ_g，量化相机频带能量
- 证书膨胀：滑移与冲击超过阈值即触发重签/降级

**IP-72 INNOV-OP（方法层）**
- 假设压力创新算子：作为后续轮次的选题机制，避免模块堆叠
- 假设登记册：显式记录 H1–H5 及其证伪条件与对应证书义务

**既有 IP 升级**
IP-63 ECPS：U(m) 升级为 U(g,m)，选择前查询步态状态
IP-60 PSE：半径查表由 r_ω(m) 变为 r_ω(m,g)
IP-51 CAR：加入 transition guard、末端冻结、切换窗口禁操作
IP-45 总线：新增 gait-state / transition-guard / slip-estimate / vibration-psd 话题
IP-61 DCL：采集滑移、足底冲击、振动谱-地形配对数据
IP-62 CCA：红队注入轮滑、模式切换抖动、传感器断流

## 3. 算法骨架

每控制周期：
1. 读 g_t, B_t, m_{t−1}, v_t, slip_t, Φ_t
2. 由 c_t 预测各地形段模式可行性与功耗
3. 对候选 (g,m) 计 rad(P_t|g,m) 与 U(g,m)，施加能量与半径约束
4. 若最优 g*≠g_t，先运行交接守卫；失败则冻结末端并 fail-closed
5. 重签 P_t(g*)，更新联合租约 ℓ_{e,g}
6. 若任一租约/守卫失败或滑移超阈 → fail-closed
PSE 按 (m_t,g_t) 签发证书，CAR 以联合证书 + 切换窗口状态守卫。

## 4. 本轮最大风险

**一句话**：把步态当作可任意选择的离散档位，会低估「模式切换期间」的位姿不连续——如果交接守卫只在名义模型下检验位姿盒相交，而真实足底冲击/轮滑让两个盒子实际不相交，Gait-Cert 会在切换瞬间失去 soundness；因此必须以保守膨胀、切换窗口禁止操作、硬件级急停三层作为最后防线。

## 2. 关键算法 伪代码

### IP-69 GRC：步态条件化半径
```
G = {W, L, T_WL, T_LW}
DRIFT = {W: 0.8, L: 2.2, T_WL: 4.0, T_LW: 4.0}   # cm/s, 标定所得
IMPACT = {W: 0.0, L: 1.5, T_WL: 2.0, T_LW: 2.0}   # cm

def gait_radius(g, m, v, dt, impact=False, slip=0.0):
    base  = r_perc[m]                    # 感知共形半径（v10）
    trans = Lv * norm(v) * dt            # 速度累积漂移
    drift = DRIFT[g] * dt + slip_gain * max(0.0, slip - slip0)
    jump  = IMPACT[g] if impact else 0.0
    return base + trans + drift + jump
```

### IP-70 LSU：步态-感知联合调度
```
def locomotion_schedule(g_t, c_t, B_t, v_t, m_prev, terrain):
    best = None
    for g in feasible_modes(c_t, terrain):          # W/L 的可行性由地形段预测给出
        if g != g_t and not can_transition(g_t, g): # 最小驻留/滞回
            continue
        for m in MODALITIES:
            rad = gait_radius(g, m, v_t, tau_p, impact=strike_ahead(g))
            if rad > rad_max:
                continue
            if not energy_lease_valid(B_t, Pg[g] + Pm[m], tau_p, E_min):
                continue
            u = (task_gain[g] + cert_gain(m, rad)) / (
                Pg[g] + Pm[m]
                + c_slip * risk_slip(g)
                + c_imp  * risk_impact(g)
            )
            if best is None or u > best.u:
                best = Candidate(g=g, m=m, u=u, rad=rad)
    return best      # None ⇒ fail-closed
```

### IP-69 切换交接守卫
```
def transition_guard(g, g_new, P_t, v_t, delta):
    grow = DRIFT[g_new] * delta + slip_margin + IMPACT[g_new]
    P_next = inflate(P_t, grow)
    if not intersects(P_t, P_next):
        return False, 'box_disjoint'
    if safety_bind(v_t, P_next, omega_t) < theta_safe:
        return False, 'unsafe_bind'
    return True, 'ok'

def guarded_switch(g, g_new, P_t, v_t, Q_safe):
    ok, why = transition_guard(g, g_new, P_t, v_t, delta=t_switch)
    if ok:
        return 'switch', g_new
    freeze_end_effector(reference_box(P_t))     # 冻结到当前安全盒
    push(Q_safe, (v_t, P_t, 'switch_frozen'))
    return 'freeze_failclosed', why
```

### IP-71 VIB-SLIP Adapter
```
def slip_estimate(odom, imu, wheel_enc, leg_odom, g):
    v_wheel = wheel_enc.v
    v_fuse  = fuse(odom, imu, leg_odom)
    slip = abs(v_wheel - v_fuse) / (norm(v_fuse) + eps)
    psd  = welch(imu)                    # 振动功率谱
    return slip, psd

def cert_inflate(slip, psd):
    e_slip = slip_gain * max(0.0, slip - slip0)
    e_vib  = vib_gain * band_energy(psd, CAM_BAND)
    return e_slip + e_vib                # 超过阈值即触发重签/降级
```

### 全局决策 Π_v11（与 v23 的 Π 对接）
```
def global_decision_v11(c_t, omega_t, B_t, v_t, M, Q_safe, g_t):
    if Q_safe and not empty(Q_safe):
        return execute_from_queue(Q_safe, c_t, B_t)
    res = locomotion_schedule(g_t, c_t, B_t, v_t, m_prev, terrain_of(c_t))
    if res is None:
        return 'fail-closed', 'energy_or_radius'
    g_star, m_star, rad = res.g, res.m, res.rad
    if g_star != g_t:
        status, info = guarded_switch(g_t, g_star, current_P, v_t, Q_safe)
        if status != 'switch':
            return 'fail-closed', info
    P_t = pose_certify(m_star, g_star, rad)
    B_prob = safety_bind(v_t, P_t, omega_t)
    if B_prob < theta_safe:
        push(Q_safe, (v_t, P_t, 'unsafe_bind'))
        return 'queued', B_prob
    return 'execute', P_t
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| GRC 半径签发 | O(1) 每 (g,m) | O(|G|·|M|) 标定表 | g 驻留期内 rad 覆盖真实误差 ⇒ P_t sound |
| LSU 联合调度 | O(|G|·|M|) 每周期 | O(|G|·|M|) | 无可行 (g,m) ⇒ fail-closed |
| 切换交接守卫 | O(1) | O(1) | 盒非空且绑定达标才放行，否则冻结 |
| VIB-SLIP | O(d_imu log d_imu) | O(d_imu) | 滑移/振动超阈 ⇒ 膨胀或降级，不静默通过 |
| 全局决策 Π_v11 | O(|G|·|M| + |M|·d) | O(|Q|) | 步态/感知/能量/安全四重约束，Fail-closed |

**正确性定理（Gait-Cert soundness）**
设步态在 [t,t+τ_p] 内保持 g 且无未守卫切换，rad(P_t|g,m) 按定义 60 给出，能量租约 ℓ_{e,g} 有效。则真实底盘位姿误差落在 P_t 内的概率 ≥1−α_p。若期间发生切换 g→g′，soundness 还要求交接守卫通过（膨胀后的两盒相交且 B(v_t,P)≥θ_safe）；守卫失败时系统冻结末端并进入 fail-closed，操作安全谓词不被触发。即：**要么 P_t 在证书义务下成立，要么系统不执行操作**，二者必居其一。

| 切换动力学模型与真实不匹配 | 高 | 以实测冲击标定 IMPACT/DRIFT；守卫按最坏情况膨胀 |
| 步态条件化半径低估 | 高 | 独立审计集分层校准；覆盖率不足即升保守档 |
| W↔L 模式抖动震荡 | 中 | 滞回 + 最小驻留时间 + 切换能耗惩罚 |
| 冻结过于频繁拉低任务吞吐 | 中 | 只在守卫失败时冻结；预测性预冻结限制在切换前窗口 |
| 滑移估计漂移/失效 | 中 | 多源冗余（轮速/IMU/足式里程计），超阈即 fail-closed |

## 6. 本轮最大风险

**一句话**：步态切换的位姿不连续是名义模型最容易低估的量，若交接守卫的膨胀系数不足以覆盖真实足底冲击与轮滑，Gait-Cert 会在切换瞬间悄悄失去 soundness；因此必须把「保守膨胀 + 切换窗口禁止操作 + 硬件级急停」作为不可省略的三层防线，而不是把它们当作可选优化。
