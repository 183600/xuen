# 第 1 轮（PACT 线 · 第 1 轮；本轮灵感：「个性化交互」×「专利布局」）

> **基线变更声明**：本文件此前承载 UniBot-SAGE 线（宇树 UniBot 桌面泛化操作；定义 U1–U12 / 引理 L1–L7 / 实验 E601–E618）。本轮灵感域转为「个性化交互」×「专利布局」，任务域随之转向**个性化物理人机协作**，故状态文件**重新基线化**到 PACT 线；UniBot 线全部编号封存停用。本线启用：定义 D1–D12、命题 R1–R6、实验 E701–E716、创新点 IP-01–IP-08。

## 0. 情报核实（检索日期 2026-11-17）

**研究面（个性化 HRI 已经很热，但热在语义层）**

1. HARMONI（ACM，2026-10）：LLM 驱动的多用户长期个性化，四模块（感知 / 世界模型 / 用户画像 / 生成），落点是**社交对话 + 养老院**。
2. HARMONY（IEEE RA-L，2026-08）：把"机器人个性"做成光谱，三层架构（多模态感知 + 离线/在线混合 RL + 参数化行为生成），用户研究显示延长交互、抹平人格类型差异。
3. Priors of U（ACM，2026-10）：因子图用户模型，从真实行为观测学空间布置 / 工具选择 / 工作流偏好，无需显式指令。
4. Parametric User Abstractions（CEUR，2026）：把用户偏好写成可解释潜参数（属性 / 上下文 / 耦合），用于**解释生成**的约束式适配。
5. SFIHILO（arXiv，2026-10）：前向-逆向人环优化，用主动查询推断个体奖励，显著减少人类实验成本。
6. 人环机器人学习博士论文（Purdue，2026-06）：把人的差异拆成**偏好异质性 / 能力异质性 / 状态不确定性**，对应个体级个性化与团队级适配。
7. Nature Communications Engineering（2026-02）：接触式机器人用模型预测博弈控制器自适应人，并证明存在一个 **assistance meta-parameter 可反向调节人自身的行为**——这是"反依赖 / 技能保持"的直接先例。

**专利面（关键约束：最直觉的方向已被宽专利占住）**

8. **Google US8996429B1**（2012 申请 / 2015 授权）"Methods and systems for robot personality development"：从用户设备取人格线索 → 云端生成机器人人格 → 可在机器人间**迁移**。权利要求宽；IntechOpen（2016）专章批评其接近"抽象概念 / 显而易见"。⇒ **任何"从用户数据生成 / 迁移机器人个性"的表述都落在它射程内，必须避开 personality / 云端迁移框架。**
9. US20210151154A1：社交机器人按"影响分数"选择 operational schema 去改变用户状态。
10. US9724824B1：按传感器识人（措辞 / 语音节奏 / 性别 / 年龄）→ 生成对话与运动脚本 → 按人类反应分类修改脚本。
11. US10898999B1：预测路人是否愿意与机器人交互，据此选择交互对象。
12. Patsnap 类人 HMI 专利景观（2026-08）：48 个家族，B25J 几乎全覆盖（47/48），G06N 19、G10L 10；2025 年 filing 峰值 29，**先例仍薄**；且"出版滞后约 18 个月"，2026 数字被低估。
13. PerspireIP 白色空间案例（2026-10）：**HRI 安全（低权利要求密度）**、**触觉 / 全身感知（低）**、**具身智能控制适配（中，但中国密、US/EP 薄）**、灵巧操作（低–中，碎片化）。

**关键结论（把两个灵感焊在一起）**

- "个性化交互"最直觉的落点（对话 / 人格 / 社交）已被 Google 宽专利 + 一批 2021–2024 申请占据，正面硬闯既无新颖性优势、又有 FTO 风险。
- 而专利景观给出的白色空间恰好是**物理与安全侧的个性化**：HRI 安全、触觉 / 接触感知、具身控制适配（US/EP 薄）。
- ⇒ 本线选一个**没人做透、也不撞 Google 人格专利**的交叉点：以**接触力 / 力矩 + 行为轨迹**为信号估计"能力-偏好画像"，只调制**物理辅助**，并把所有个性化**投影到安全认证集内**。一句话：**个性化"怎么帮你动"，而不是"机器人是什么性格"。**

## 1. 直觉与动机（两灵感的第一性原理）

**灵感 1 ·「个性化交互」→ 交互质量取决于"机器人行为与具体这个人的匹配"，匹配量是隐变量**

直觉：同一个固定策略，对强壮熟练的用户是"帮倒忙"（限制太死、太慢），对虚弱 / 手抖的用户是"不够用"（辅助不足、易失稳）。真正的个性化不是换语气 / 换人格，而是让**阻抗 / 辅助力 / 引导强度 / 主动性 / 时机**随人变。

严谨化：设用户隐画像 `u = (u_cap, u_pref, u_trust, u_safe)`。"个性化" = 在后验 `p(u | H_t)` 下，选择一个在**安全认证集**内使期望效用最大的控制调制 `m(u)`。三个要点：(a) `u` 不可直接观测，只能从接触力 / 力矩、轨迹偏差、恢复事件、稀疏偏好反馈中推断；(b) `u` **非平稳**（人会学习、疲劳、改变主意）；(c) 辅助本身会改变 `u`（依赖 / 技能萎缩），所以个性化是一个**闭环耦合**问题，不是一次性回归。

**灵感 2 ·「专利布局」→ 研究选题本身就是一次"权利要求设计"**

直觉：若一项研究天然落在别人宽权利要求的射程内，再好的科学也换不成资产；反过来，"白空间"提示的不只是法律机会，更是**被同行忽视的科学问题**。

严谨化：对候选方向定义白空间分 `WS = 新颖性 × 低权利要求密度 × 技术效果可测性`，用它给选题排序；并要求每个核心机制都能写成一个**技术特征组合**（有明确技术效果、可被侵权比对）。这把"专利布局"从申报动作前移为**选题约束**：**只做能被清晰权利要求化的机制，且优先做别人没占的安全 / 物理侧**（原则 P6）。

**合成**：交互（把人变成可估的隐画像）× 物理（个性化限制在辅助控制而非人格）× 安全（个性化投影进 CBF 安全集）× 专利（机制设计成可权利要求化的特征组合）⇒

**画像层**（接触 / 行为 → 能力-偏好后验）→ **调制层**（阻抗 / 辅助 / 主动性）→ **安全层**（CBF 投影 + 备份控制器）→ **IP 层**（白空间评分 + 权利要求树）。

## 2. 瓶颈在哪里（为什么不是"再做一个个性化对话机器人"）

| 观察 | 含义 |
|---|---|
| 现有个人化 HRI 多集中在对话 / 人格 / 社交（HARMONI / HARMONY / Priors of U） | 语义侧拥挤且被宽专利覆盖 ⇒ 差异化不在语义 |
| 专利白空间在 HRI 安全 / 触觉接触 / 具身控制适配（US/EP 薄） | **物理侧个性化既缺研究也缺权利要求** ⇒ 机会 |
| 个性化辅助的经典风险是"越帮越差"（依赖 / 技能萎缩），Nature Comms Eng 已证 meta-parameter 能反向调节人 | 评估若只看"带辅成功率"会奖励过度辅助 ⇒ 指标必须含"撤辅后能力" |
| 人的能力 / 偏好**非平稳**（学习 / 疲劳 / 情境） | 一次性画像必失效 ⇒ 持续估计 + 不确定性感知 |
| 安全研究强调"个性化不许破坏安全" | 个性化与安全表面冲突 ⇒ 用**投影式**而非端到端学一个更激进的策略 |

**三条可执行结论**

- **T1 战场在物理辅助，不在人格**：避开 Google 宽专利，且正对白空间。
- **T2 安全投影是核心机制而非附属**：它同时是科学保证（前向不变性）与专利新颖点（特征组合）。
- **T3 个性化必须可撤销、可度量、抗依赖**：否则收益只是适应 / 新奇效应伪影。

## 3. 研究问题（轮次版）

- **Q1（可估性）**：仅用接触力 / 力矩 + 轨迹偏差 + 稀疏偏好查询，能否把能力-偏好画像估到"足以支撑调制"的精度，并给出校准的不确定性？
- **Q2（安全-个性化张力）**：CBF 安全投影会不会把个性化可用空间压没？可兑现增益的理论上界与实证比例是多少？
- **Q3（查询经济学）**：在"每次反馈都有负担"的约束下，主动查询能省多少样本？
- **Q4（反依赖）**：如何在不牺牲当期任务成功的前提下，让辅助随用户能力增长而退坡？
- **Q5（迁移与合规）**：画像跨用户 / 跨形态迁移时，如何保证安全不被"抄坏"？本地化 / 联邦能否满足隐私？
- **Q6（IP 可执行性）**：本机制能否写成区别于 US8996429 / US9724824 / US20210151154 的权利要求组合？FTO 风险点在哪？

## 4. 设计原则

- **P1 只调物理辅助**：个性化只作用于阻抗 / 辅助力 / 引导 / 主动性，不碰"人格 / 云端迁移"（专利避让 + 科学聚焦）。
- **P2 安全与画像解耦**：安全由投影保证，**不依赖** `û` 准不准；画像估计再差也不能突破安全集。
- **P3 不确定性感知调制**：调制强度 ∝ 后验置信度，低置信退回保守（绝不"自信地帮倒忙"）。
- **P4 双指标评估**：带辅成功率 + 撤辅能力保持；禁止只报前者。
- **P5 查询经济学**：按"单位负担信息增益"选查询，硬预算上限。
- **P6 研究-IP 协同**：每个核心机制先过"可权利要求化"检查，再排优先级。
- **P7 隐私默认本地**：默认端侧，联邦为可选项，画像可删可携。

## 5. 最小可提交闭环（MVP）与退化链

**MVP = IP-02（安全投影个性化）+ IP-01（画像估计）+ IP-03（主动查询）+ IP-07（IP/FTO 看板）+ 基线辅助控制器。**

**严格退化链（任一环节不可用 ⇒ 行为回退而非漂移）**：
- Level-0 画像低置信 ⇒ 退回保守固定阻抗（无调制）；
- Level-1 查询预算耗尽 ⇒ 用层级先验冷启动；
- Level-2 安全投影求解超时 / 不可行 ⇒ 退回停机或保守阻抗（安全优先）；
- Level-3 跨形态迁移未重认证 ⇒ **禁止迁移**，用目标形态现场重估；
- Level-4 整条新链路失效 ⇒ 退回纯基线辅助控制器（永远保留的安全网）；
- Level-5 IP 检查不通过（落入在先权利要求）⇒ 降级为防御性公开 + 调整特征组合。

## 6. 预期贡献（可验收）

1. 把"个性化"从语义层搬到**接触物理层**，给出**安全不变的投影式个性化**框架（科学 + 专利双新）。
2. 给出"安全-个性化可兑现增益"的界与实证，**诚实暴露二者的张力**而非掩盖。
3. 一套**反依赖**的辅助退坡机制与"带辅成功率 + 撤辅能力"双指标评估。
4. 一个把**专利白空间评分用于选题**的可复用方法（研究-IP 协同）。
5. 一个含**安全违规率 / 撤辅迁移 / 查询负担**的个性化 HRI 基准。

## 7. 本轮最大风险

**一句话**：本轮把赌注压在"用接触与行为信号估出可迁移的能力-偏好画像、并在安全投影内变现"，但**安全投影可能把个性化可用空间压得极小，而 HRI 评估又天然奖励"多帮忙"**，于是我们可能测出一个主要来自"用户主动适应机器人 / 新奇效应"的伪增益，而非真正可复现的个性化收益。

## 8. 下一轮迭代计划（深化与修剪，不推倒重来）

- **深化**：把 D1–D12 落到具体控制器与仿真环境；把 R2 的"可兑现增益上界"做成可计算量（安全集直径 × 画像对齐度）；用 2–3 个真实专利做 claim chart 练手，验证 R6 的区分度逻辑。
- **修剪预案**：若画像在接触信号下不可辨识（R3 下界差于"少量显式档位选择"），则退化为**极简档位个性化**（仍保留安全投影与反依赖纪律），把资源压到 IP-02 / IP-07。
- **保留项**：IP-02（机制核心）、IP-01（信息价值最高）、IP-07（本灵感直接产物）三项在任何情况下不砍。

# 第 1 轮产物 · 创新点清单 v1（PACT 线）：**PACT — Personalized Assistance via Constrained Transfer**

> **PACT = Personalized Assistance via Constrained Transfer**（约束迁移式个性化辅助）：把"个性化"编译成**物理辅助参数的后验调制**，并用**安全投影**保证个性化永不突破安全集。名字里的 Constrained Transfer 双关：一层是**控制约束**（CBF 投影），一层是**画像迁移**（跨用户 / 跨形态且必须重新安全认证）。
> **基线声明**：本文件此前为 UniBot-SAGE 线（桌面泛化操作；U/L/E 编号），与本轮任务域不同源，已封存；本线启用 D（定义 1–12）、R（命题 1–6）、E（实验 701–716）新编号。
> **数据来源纪律**：研究现状与专利现状均检索于 **2026-11-17**，来源见 §10；专利法律状态一律以"公开记录 / 假设"表述，**不构成法律意见**。

## 0. 本轮结论摘要

**一句话路线**：不做"个性化人格 / 对话"（已被 US8996429 等宽专利占住），改做**个性化物理辅助**——用接触力 / 力矩与行为轨迹估计"能力-偏好画像"，只调制阻抗 / 辅助力 / 引导 / 主动性，并把调制**投影到控制障碍函数（CBF）认证的安全集内**；同时用**专利白空间评分**把选题、机制与权利要求一体化设计。

**为什么是这个组合（研究面 + 专利面双重证据）**：

| 证据 | 数值 / 事实 | 推出的设计 |
|---|---|---|
| 个性化 HRI 研究集中在对话 / 人格 / 社交（HARMONI、HARMONY、Priors of U） | 语义层拥挤、差异化低 | 不在语义层竞争 → **物理辅助层**（P1） |
| Google US8996429B1 覆盖"从用户数据生成并迁移机器人人格" | 宽权利要求、云端迁移 | **避开 personality / 云端框架**，改"能力-偏好 → 物理控制"（P1） |
| 专利白空间：HRI 安全（低密度）、触觉接触（低）、具身控制适配（US/EP 薄） | PerspireIP 2026-10、Patsnap 2026-08 | **安全 + 接触 + 控制适配**三交叉点（T1） |
| 接触式辅助存在"越帮越差"风险；Nature Comms Eng 已证 assistance meta-parameter 可反向调节人 | 2026-02 | **反依赖退坡 + 双指标（带辅 + 撤辅）**（IP-04 / P4） |
| 个性化收益易与"用户适应机器人"混淆 | 交互本质 | 必须用**撤辅迁移测试**拆解（R6） |

**合规与伦理红线**：涉及人体接触实验 → 先仿真、后 IRB 审批的真机研究；安全集外一律不执行；画像本地存储、可删除、可携带；不把生理数据用于歧视性定价 / 保险等二次用途。

## 2. 创新点详述

### IP-01 · CAPS 接触式能力-偏好画像（P0）

- **动机**：个性化 HRI 的现状几乎都在估"语义偏好"（喜欢什么语气 / 什么解释）。但接触式协作里**决定成败的是能力侧隐变量**：舒适力 `f*`、关节活动度、震颤（幅值 / 频率）、反应延迟 `τ_r`、最大安全速度。这些量从对话里问不出来，只能从**物理交互信号**里读。
- **与现有方案的差异**：现有做法是把用户画像建在**语言 / 行为偏好**上（HARMONI 的 speaker profile、Priors of U 的布置偏好）；我们把画像主锚点放在**接触动力学**上（力/力矩统计、轨迹偏差、恢复事件、震颤谱），偏好作为低维附加项。这样既避开语义侧拥挤，又天然落在"触觉 / 接触感知"白空间。
- **技术可行性**：中–高。所需信号（末端力/力矩、关节位置/速度、EE 轨迹、任务事件）在带力传感的协作臂上现成；震颤可由 F/T 的 PSD 提取；反应延迟可由"扰动→用户纠正"的时序估计。难点是**个体差异与任务差异混杂** ⇒ 用层级模型（个体参数 + 任务上下文）分离。
- **所需资源**：仿真（MuJoCo / Isaac）+ 带 F/T 的协作臂；小算力（编码器 ResNet/MLP 级）；数据 = 20–40 名受试 × 多任务（先仿真合成，再真人小样本）。
- **落地步骤**：①仿真中构造参数化"虚拟用户"（不同 `f* / ROM / tremor / τ_r`）产生接触轨迹；②训练能力编码器 + 不确定性头（异方差 / 深度集成）；③真人小样本校准；④可靠性图与 ECE 校准；⑤做"跨任务一致性"检验（同一人在不同任务上的画像是否收敛到同一 `u`）。
- **风险**：①接触信号对"能力"的可辨识性可能不足（不同能力组合产生相似轨迹）⇒ 主动设计**激励性任务**（需要特定能力的子任务）提升可辨识性；②生理/能力数据敏感 ⇒ 本地化 + 最小化采集。

### IP-02 · SAP 安全投影个性化（P0，核心）

- **动机**：个性化与安全表面冲突——越贴合个人，越可能贴近其能力边界。若用端到端学习一个"更激进策略"，安全无法证明。正解是**把个性化限制在"期望动作"层，再用安全过滤器投影**：个性化只能建议，不能越权。
- **与现有方案的差异**：常见做法是"个性化 = 换一个策略 / 换一组增益"，安全靠训练与调参；我们把个性化与安全**结构性解耦**：`a* = SafetyFilter(Π(u; π0)(x))`，`SafetyFilter` 用 CBF-QP 与备份控制器保证前向不变性。**安全证明不依赖 `û`**，这是可证明的强性质（R1）。
- **技术可行性**：高（理论成熟）。CBF / 安全滤波器是标准工具（Ames 等）；QP 实时可解（小规模）。难点在**高相对度约束**与**接触模式切换**下的 CBF 设计 ⇒ 用高阶 CBF（HOCBF）与模式相关的安全集。
- **所需资源**：控制实现 + 仿真；算力极小（QP 微秒级）；无需新数据。
- **落地步骤**：①定义安全集（关节限位、速度、接触力上限、人机最小间距、工具禁区）；②为每个模式设计 `h(x)` 与备份控制器；③实现 CBF-QP 滤波器；④把 IP-01 的调制接到 `a_des`；⑤对抗性测试：故意注入错误 `û` / 极端画像，验证 0 违规；⑥把"投影导致的收益损失"量化为 R2 的 headroom。
- **风险**：①**headroom 过小**——安全集太紧时个性化几无空间，这是本线最大科学风险（见 §9 与 R2）；②HOCBF 参数（`α` 增益）选差会过度保守或抖动 ⇒ 用可达性分析调参；③模式切换导致可行性丢失 ⇒ 加"安全模式回退"。

### IP-03 · ABQ 负担预算主动查询（P0）

- **动机**：画像不能全靠被动观测——有些偏好（"你希望我多主动？"）没有行为证据。但每次打断用户都有负担，且过度询问会降低体验。所以查询是**经济问题**，不是越多越好。
- **与现有方案的差异**：偏好学习常默认"查询免费"；我们显式建模**负担预算** `B` 与查询成本 `cost(q)`，按"单位负担信息增益"选查询，并允许**放弃查询**退回先验。
- **技术可行性**：高。主动偏好学习（如 Sadigh 等的主动偏好查询）+ 贝叶斯实验设计已成熟。
- **所需资源**：小；与 IP-01 共用模型。
- **落地步骤**：①定义候选查询集（轨迹对比较 / 档位选择 / 二选一）；②估计每个查询的后验信息增益；③除以成本（时间 + 认知负担）排序；④硬预算停止准则；⑤验证"少问也够"。
- **风险**：信息增益模型错设 ⇒ 问了没用的问题；缓解：在线校准查询价值，并在仿真里预演。

### IP-04 · AID 反依赖辅助退坡（P1）

- **动机**：长期高辅助会让用户技能萎缩、并对机器人过度依赖（自动化自满）。这不是伦理装饰，而是**长期效用**问题：撤辅后用户崩溃，等于系统没真正"帮到人"。
- **与现有方案的差异**：多数辅助系统把"当期任务成功"当唯一目标，辅助强度只增不减；我们引入**辅助 meta-parameter 的退坡调度**，其依据是**撤辅能力**（unaided competence），而非带辅表现（避免"机器人做的被你算成你能做"）。
- **技术可行性**：中。需要纵向数据与"辅助开关"实验设计。
- **所需资源**：纵向用户研究；小算力。
- **落地步骤**：①定义能力估计量（仅用未辅助试验）；②设计退坡律 `β_t = β_0·exp(-λ·competence_t)` 并加下限；③A/B：恒定高辅助 vs 退坡；④测第 N 次会话的**撤辅迁移**；⑤检验是否牺牲当期成功。
- **风险**：退坡过快导致短期失败 / 挫败 ⇒ 设"能力置信下界"才退坡 + 失败则暂缓；测量污染 ⇒ 严格区分辅助/未辅助试验。

### IP-05 · TRS 重认证迁移（P1）

- **动机**：画像的价值在迁移（新用户冷启动、换机器人/换末端）。但把 A 系统的画像直接搬到 B 系统是**危险的**：动力学、传感、执行器都变了，安全集随之变。
- **与现有方案的差异**：Google US8996429 的核心正是"人格跨机器人迁移"，但**不做安全重认证**；我们主张"迁移 ≠ 复制"——迁移只提供**先验**，必须在目标系统上**重新验证 CBF** 才能启用，否则退回保守。
- **技术可行性**：中。跨形态映射 `R` 可用少量配对数据学；安全重认证用目标系统模型做离线可达性验证。
- **所需资源**：多形态平台（或仿真多形态）；中算力。
- **落地步骤**：①学跨形态映射 `R`；②目标系统 CBF 重认证（离线可达性 + 在线监控）；③未通过则保守回退；④测冷启动加速与 0 违规；⑤做"未重认证"的对照以证明必要性（R5）。
- **风险**：映射外推失效 ⇒ 限制在相似形态簇内；重认证成本高 ⇒ 预计算认证缓存。

### IP-06 · PLP 隐私本地个性化（P2）

- **动机**：画像含能力 / 生理 / 偏好，属敏感数据；集中式训练既不合规也不被用户信任。
- **与现有方案的差异**：默认**端侧**估计与存储，联邦聚合只上传梯度/统计量；画像可导出、可删除（被遗忘权）。
- **技术可行性**：高（工程）；联邦效用损失需评估。
- **落地步骤**：①端侧推理与存储；②联邦聚合（可选）；③删除 / 导出接口；④效用-隐私权衡实验。
- **风险**：联邦导致画像质量下降 ⇒ 混合：端侧精调 + 全局先验；隐私攻击（成员推断）⇒ 差分隐私噪声。

### IP-07 · PLat 专利格与 FTO 看板（P0，方法论核心）

- **动机**：本灵感要求"专利布局"不是事后补票，而是参与选题。研究若落在宽权利要求射程内，等于替别人做验证。
- **与现有方案的差异**：多数研究组只做 FTO 检索（防守）；我们做**正向的白空间评分 + 权利要求树设计**（进攻 + 防守 + 设计绕行），并把评分反馈给选题。
- **技术可行性**：高（流程 + 检索工具）。风险在法律判断的专业性 ⇒ 需专利律师复核。
- **落地步骤**：①建立 3 个检索簇（HRI 安全 / 接触感知 / 控制适配）；②对每个候选机制做 claim chart vs 主要先例；③计算 `WS`（D12）；④设计独立权利要求 + 从属权利要求树；⑤出具 FTO 风险登记与设计绕行方案；⑥每轮迭代更新。
- **风险**：把"白空间"误当"无先例" ⇒ 必须查非专利文献（论文 / 开源）与在审申请；权利要求写得过宽会被驳回、过窄易被绕 ⇒ 分层布局。

### IP-08 · PACT-Bench 个性化 HRI 基准（P0）

- **动机**：没有统一的"个性化"评测，导致各说各话；且现有评测奖励"多帮忙"，掩盖依赖与安全代价。
- **与现有方案的差异**：同时评**带辅成功、撤辅能力保持、安全违规率、查询负担、跨用户公平性**五类指标，并内置"用户会适应机器人"的耦合模型，专门暴露伪增益。
- **技术可行性**：中–高。仿真可控；真机子集用于锚定。
- **落地步骤**：①仿真"虚拟用户群"（能力/偏好/学习率各异）；②多任务（搬运 / 拧转 / 插装 / 共享工作台）；③指标实现与统计；④"适应型用户"模型；⑤跨方法排行榜。
- **风险**：仿真用户模型过于理想 ⇒ 用真人小样本校准；指标被刷 ⇒ 预注册指标与门槛。

## 3. 符号与定义（D1–D12）

| 符号 | 含义 |
|---|---|
| `u` | 用户画像 `(u_cap, u_pref, u_trust, u_safe)` |
| `H_t` | 到 t 的交互历史（接触、轨迹、事件、反馈） |
| `p(u\|H_t)` | 画像后验（带不确定性） |
| `Π(u; π0)` | 个性化调制算子（作用于基线辅助策略 `π0`） |
| `m` | 调制参数（阻抗 `K_d,D_d`、辅助缩放 `β`、虚拟夹具刚度、主动性） |
| `h(x)` | 控制障碍函数；安全集 `C={x:h(x)≥0}` |
| `SF(·)` | 安全过滤器（CBF-QP 投影） |
| `B` | 单会话查询负担预算 |
| `β_t` | 辅助强度（反依赖调度的被控量） |
| `s_t` | 用户撤辅能力（unaided competence） |
| `R` | 跨形态画像映射 |
| `WS` | 白空间分（选题用） |

**定义 D1（用户画像）** `u = (u_cap, u_pref, u_trust, u_safe)`，其中 `u_cap = (f*, ROM, tremor(amp,freq), τ_r, v_max)`，`u_pref = (β*, v*, initiative, modality)`，`u_trust` 为过度依赖倾向，`u_safe` 为最小间距 / 最大速度容忍。`u` 为**潜变量**，只有后验。

**定义 D2（交互信号）** `H_t = {(F_t, x_t, ẋ_t, e_t, c_t)}`：末端力/力矩、末端位姿、速度、用户纠正事件、可选稀疏反馈。能力侧特征 `φ_cap(H_t) = [wrench_stats, traj_deviation, recovery_events, tremor_psd]`。

**定义 D3（能力估计器）** `û_cap ~ q_ψ(·|φ_cap(H_t))`，输出分布而非点估计（异方差或集成）。

**定义 D4（偏好模型）** 偏好似然 `P(≻ | u, q)`：用户对查询 `q`（轨迹对 / 档位）的选择概率；`u_pref` 的共轭/逻辑参数化。

**定义 D5（个性化调制算子）** `m = Π(u; π0)`，只改 `(K_d, D_d, β, 虚拟夹具刚度, 主动性)`；**不改任务空间、不改安全约束**。

**定义 D6（安全证书）** 安全集 `C = {x : h(x) ≥ 0}`，`h` 连续可微；存在备份控制器 `π_b` 使 `C` 控制不变。

**定义 D7（安全过滤器）** `SF(x, a_des) = argmin_{a∈A} ‖a − a_des‖²  s.t.  L_f h + L_g h·a + α(h) ≥ 0`。

**定义 D8（安全投影个性化）** `a* = SF(x, Π(u; π0)(x))`。**关键：`SF` 不接收 `u`** ⇒ 安全与画像误差解耦。

**定义 D9（负担预算与主动查询）** 查询策略 `q* = argmax_{q∈Q} IG(q)/cost(q)  s.t.  Σcost ≤ B`；`IG` 为后验期望信息增益。

**定义 D10（反依赖调度）** `β_t = clip(β_0·exp(−λ·ŝ_t), β_min, β_max)`，`ŝ_t` 仅由**未辅助**试验估计。

**定义 D11（重认证迁移）** `u_B = R(u_A)`；仅当 `Verify_CBF(B, u_B) = True` 才启用，否则 `u_B ← u_B^{cons}`。

**定义 D12（白空间分）** `WS(C) = Nov(C) · (1 − Density_US/EP(C)) · Effect(C)`，`C` 为权利要求元素集合；`Nov` 为与先例的重叠补，`Effect` 为技术效果可测性。

```python
# ===== PACT 主控制器：画像 → 调制 → 安全投影 → 反依赖 =====
class PACTController:
    def __init__(self, base_policy, profile_model, cbf, backup, aid):
        self.pi0 = base_policy
        self.q   = profile_model          # IP-01：p(u|H)
        self.cbf = cbf                    # IP-02：安全集与 h
        self.backup = backup
        self.aid = aid                    # IP-04：反依赖调度
        self.H = {uid: [] for uid in ...} # 每用户历史（IP-06：端侧）

    def reset(self, user_id):
        self.uid = user_id
        self.H[user_id] = []
        self.post = self.q.prior(user_id)  # 层级先验冷启动

    def step(self, x, contact, feedback=None):
        self.H[self.uid].append((x, contact))
        # ---- IP-03：按信息增益/负担决定是否查询（可选）----
        if feedback is not None:
            self.post = self.q.update(self.post, feedback)
        elif self.q.should_query(self.post, budget_left):
            return QueryAction(self.q.best_query(self.post))
        # ---- IP-01：能力后验更新 ----
        self.post = self.q.update_capability(self.post, self.H[self.uid])
        u, conf = self.post.mean, self.post.confidence()
        # ---- IP-02：置信度收缩的个性化调制 ----
        m = modulate(u, shrink=conf)            # P3：低置信→向保守收缩
        a_des = self.pi0(x, m)
        # ---- IP-02：安全投影（不接收 u！）----
        a_safe = self.safety_filter(x, a_des)   # D7
        # ---- IP-04：反依赖退坡 ----
        beta = self.aid.schedule(self.competence_est())
        a_safe = rescale_assistance(a_safe, beta)
        return a_safe

    def safety_filter(self, x, a_des):
        # min ||a - a_des||^2  s.t.  Lf h + Lg h a + alpha(h) >= 0,  a in A
        a = solve_qp(x, a_des, self.cbf)
        if a is None:                 # 不可行 → 安全回退
            return self.backup(x)
        return a
```

```python
# ===== IP-01：接触式画像（分布输出 + 校准）=====
class ProfileModel:
    def __init__(self, encoder, prior):
        self.enc = encoder            # F/T + 轨迹 + 事件 → 特征
        self.prior = prior            # 层级先验（跨用户共享）

    def update_capability(self, post, H):
        phi = features(H)             # wrench_stats, traj_dev, recovery, tremor_psd
        mu, logvar = self.enc(phi)    # 异方差头
        return fuse(post, Normal(mu, exp(0.5 * logvar)))  # 贝叶斯融合

    def should_query(self, post, budget_left):
        return budget_left > 0 and self.max_IG(post) / self.cost_min(post) > self.tau_q

    def best_query(self, post):
        return max(self.candidates(), key=lambda q: self.IG(post, q) / self.cost(q))
```

```python
# ===== IP-02 / R1：CBF-QP 安全投影 =====
def solve_qp(x, a_des, cbf):
    Lf, Lg = cbf.lie_derivatives(x)
    h = cbf.h(x); alpha = cbf.alpha(h)
    # 变量 a；目标 0.5||a-a_des||^2；约束 Lf + Lg a + alpha >= 0；a ∈ [a_lo, a_hi]
    return qp_solver(a_des, Lf + alpha, Lg, cbf.box(x))
```

```python
# ===== IP-04：反依赖退坡（只用撤辅能力）=====
class AID:
    def __init__(self, beta0, lam, lo, hi):
        self.beta0, self.lam, self.lo, self.hi = beta0, lam, lo, hi

    def schedule(self, s_hat):
        beta = self.beta0 * math.exp(-self.lam * s_hat)
        return min(self.hi, max(self.lo, beta))

def competence_est(trials):
    unaided = [succ for succ, aided in trials if not aided]   # 关键：排除带辅
    return mean(unaided) if unaided else 0.0
```

## 5. 推导（R1–R6）

**命题 R1（个性化下的安全不变性）** 设安全集 `C={x:h(x)≥0}` 在备份控制器下控制不变，`α` 为扩展类-`K` 函数，则对**任意**期望动作 `a_des`（无论来自何种画像 `û`），`SF` 的输出都满足 `ḣ + α(h) ≥ 0`，从而闭环保持 `C` 前向不变。**推论**：安全**不依赖**画像估计精度；画像错误只影响性能，不影响安全性。∎

**命题 R2（个性化可兑现增益的 headroom 上界）** 令 `a^cons` 为保守基线的动作、`a^{u*}` 为用户最优的可行动作，`Π` 关于 `u` 为 `L_Π`-Lipschitz。则在安全集内可兑现的个性化收益满足
`benefit ≤ L_Π·‖û − u*‖ + diam(𝒜_safe ∩ 𝒜_personal)`，
且当安全集 `𝒜_safe` 收紧时第二项单调下降。**推论**：安全-个性化张力是**结构性的**，必须把 `diam(𝒜_safe ∩ 𝒜_personal)` 作为设计变量测量，而不能假定个性化必然有收益。∎

**命题 R3（画像估计的样本复杂度，下界直觉）** 在 `d` 维画像、似然 `L`-Lipschitz 且查询有界的条件下，达到偏好误差 `ε` 所需查询数为 `Ω(d/ε²)`；主动选择（最大化单位负担信息增益）在逻辑偏好模型下可把常数因子改善到 `O(d log(1/ε))`。**推论**：`d` 必须小（用低维结构化画像而非黑箱高维向量），否则查询预算 `B` 必然不够。∎

**命题 R4（反依赖退坡的长期占优）** 设用户能力动力学 `s_{t+1} = s_t + η(1−β_t)·practice − δ·β_t·atrophy`（`η,δ>0`）。则存在 `β*<β_max`，使单调退坡调度在足够长时域上的累计 `s_T` 严格大于恒定高辅助 `β=β_max`。**推论**：若只看当期成功，恒定高辅助最优；若看长期能力，退坡占优 ⇒ 评估必须跨时域（P4）。∎

**命题 R5（迁移必须重认证）** 若源/目标系统动力学差以模型误差 `Δ` 有界，则把源画像直接用于目标系统时，安全约束的裕度损失最多 `O(Δ)`；一旦 `Δ` 超过备份控制器的鲁棒裕度，存在使 `C` 被破坏的初始状态。**推论**：跨形态迁移只能作为**先验**，必须在目标系统重新验证 CBF（D11）或加鲁棒裕度。∎

**命题 R6（个性化收益的可识别性 / 抗混淆）** 若评估只统计"带辅任务成功率"，则任何提高辅助强度 `β` 的系统都会显得更好，即使 `s_t` 不增长。要识别真实个性化收益，必须同时报告 (i) 撤辅迁移成功率 `P_succ(β=0)`、(ii) 辅助强度轨迹 `{β_t}`、(iii) 用户适应项（同一用户在固定策略下的技能漂移）。**推论**：单指标评测在个性化场景下**系统性偏袒过度辅助**；PACT-Bench 必须内置三指标（IP-08）。∎

### 6.1 先例地图（claim focus vs 本线）

| 先例 | 保护焦点 | 与本线关系 | 应对 |

| 学术：主动偏好学习（Sadigh 等） | 偏好查询算法 | 公知 | 主张"负担预算 + 安全投影"的组合 |

### 6.2 白空间定位

- PerspireIP（2026-10）四簇白空间：**HRI 安全（低）**、触觉 / 全身感知（低）、灵巧操作（低–中）、具身控制适配（中，但 **US/EP 薄、中国密**）。
- Patsnap（2026-08）：类人 HMI 仅 48 家族，B25J 覆盖 47，G06N 19、G10L 10；2025 filing 峰值 29；**先例薄**。
- ⇒ **本线落在"HRI 安全 × 接触感知 × 控制适配"的三交叉**，属于**低密度 + 薄先例 + 强技术效果**的甜点区（D12 的 `WS` 高）。

### 6.3 权利要求树（草案）

- **权 1（方法，独立）**：①获取机器人与用户之间的**接触交互信号**；②由该信号估计**能力-偏好画像**（含不确定性）；③据此计算**个性化期望控制**；④用**控制障碍函数约束 + 备份控制器**把期望控制**投影**到安全认证集；⑤执行。
- **权 2（从属）**：查询选择按**单位负担信息增益**并受预算上限约束（IP-03）。
- **权 3（从属）**：辅助强度按**撤辅能力**（而非带辅表现）退坡（IP-04）。
- **权 4（从属）**：跨形态迁移前**重新验证安全集**，未通过则回退保守（IP-05）。
- **权 5（从属）**：多用户识别 + **端侧画像隔离** + 可删除（IP-06）。
- **权 6（系统）**：处理器 + 存储器实现权 1–5。
- **权 7（CRM）**：非暂时性存储介质实现权 1–5。
- **防御性公开**：通用画像特征工程、通用 CBF 细节（避免被他人用窄专利反堵）。
- **技术秘密**：画像编码器结构、震颤/延迟的具体特征与阈值。

### 6.4 区别技术特征（对每个主要先例 ≥2 个）

| 先例 | 区别特征 1 | 区别特征 2 |
|---|---|---|

### 6.5 申请策略与 FTO

- **地域**：优先 **US + EP**（白空间薄、市场大）；**监控 CN**（具身控制适配密集，可能构成 FTO 风险）；PCT 12 个月内布局。
- **时序**：先递交**临时申请**锁定优先权，再补实验数据；论文投稿与申请错峰（避免自我公开破坏新颖性，注意各地宽限期差异）。

- **与灵感的闭环**：`WS` 评分（D12）每轮更新，**低 WS 的方向直接降优先级**——这是"专利布局"对研究选题的真实约束。

## 9. 风险登记册与剪枝预案

| 风险 | 概率 | 影响 | 对冲 |

| **安全-个性化 headroom 过小**（最大科学风险） | 中高 | 高（收益≈0） | 把 `diam(𝒜_safe∩𝒜_personal)` 当设计变量先测；选安全集有裕度的任务；R2 显式报告 |

- **必保**：IP-02（机制核心）、IP-01（信息价值）、IP-07（本灵感直接产物）。

- **暂存**：IP-06（工程化后置）。
- **一票否决**：任何 E703/E707 安全违规 ⇒ 该机制下线。
