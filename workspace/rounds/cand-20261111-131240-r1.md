# 第 55 轮（承接第 54 轮 v31 GroundEdge-GenSim+++；新灵感循环第 1 轮；本轮灵感：「可解释性」×「大语言模型」）

> 第 54 轮已把技能组合推进到动作空间剖面 `α_S`、组合图 `G_S`、云边映射 `γ_ce` 与联合证书 `J`，并用反向解释 `Explain` 驱动重剖分。本轮引入 **可解释性与大语言模型**：让 LLM 作为解释与计划的“提案者”，让形式化验证器作为“裁决者”，把“看起来合理”的解释升级为“可干预验证的忠实解释证书”。核心矛盾：**H22**：LLM 生成的解释流畅但未必忠实（unfaithful），若直接写入证书会产生「解释性洗白」（faithwashing）——比没有解释更危险，因为它制造了不可审计的虚假信任；**H23**：LLM 在语义空间做规划，而边端在动作/鲁棒性空间执行，语义-动作接地缺口使“可解释的计划”可能形式化不可部署。

## 0. 直觉与动机

**灵感 1（忠实性 = 解释的“可证伪性”）**
直觉：一个好解释不是“说得通”，而是“指向真正起作用的因果”。若解释说“失败是因为抓取角度偏了”，那么固定其它变量、只把角度调回，结果应显著改善（充分性/对比性）；把解释没提到的变量随便扰动，结果不应大变（必要性/最小性）。这把解释从一段文本变成一条**可做 do-干预实验的假设**。严格化后即定义 122 的 `(ε,δ,γ)`-忠实性。这样，“可解释性”第一次成为可测量、可否决的量，而不是主观感受。

**灵感 2（LLM 只做提案者，不做裁决者）**
直觉：LLM 擅长提出候选原因、生成计划补丁、把日志翻译成人话，但它无法保证自己忠实。因此把 LLM 放在“提出假设”的位置，把形式化验证器（仿真 do-干预 + 符号接地 + 证书检查）放在“接受/拒绝”的位置，形成 **propose-verify 分离**。幻觉被限制在提案层，永远进不了证书层。这正是把“可解释性”与“大语言模型”接在一起最稳的架构：LLM 提供覆盖与语言，验证器提供 soundness。

**灵感 3（解释稳健性作为新的鲁棒性维度）**
直觉：如果动作轻微扰动就让解释引用的原因集合完全换掉，那么这个解释是脆弱的，不能用于跨场景迁移，也不能作为证书。把解释稳定性 `ρ_exp` 加入第 53 轮鲁棒性谱，作为维度 `d_exp`：鲁棒的不只是结果，还有“结果为何如此”的因果归因。

**灵感 4（语义-动作接地证书）**
直觉：LLM 计划里的“先对准、再夹取”是**语义谓词**，必须被映射到 `α_S` 上的动作子集与前置/后置条件。映射不上、覆盖不足的语义谓词就是“悬空承诺”，必须拒绝。接地缺口 `G_gap` 把“语言上说得通”与“动作上做得到”明确分开。

**灵感 5（验证过的反事实记忆）**
直觉：把通过验证的 `(失败轨迹, 忠实原因, 修复补丁)` 存为反事实库，检索增强给 LLM 作为上下文，使解释随轮次变好；但记忆条目自带信任分，漂移或过期即降权，且**记忆只做提案上下文，不做证书证据**，防止“记忆污染 → 污染证书”的二次洗白。

**灵感 6（解释金字塔与证书分层）**
直觉：在第 54 轮的鲁棒性层 `𝕃` 与动作协同层 `𝔸` 之上，加一层 **解释层 `𝕏`**：`𝕏_0` 原始日志、`𝕏_1` 类型化解释、`𝕏_2` 干预验证、`𝕏_3` 信任校准证书。低层永远不能被跳过去直接声称高层结论；LLM 只能在 `𝕏_1` 提案，`𝕏_2/𝕏_3` 只能由验证器写入。

## 1. 形式化定义（增量：定义 121–127）

**定义 121（类型化解释对象）**
解释 `E = (C, r, π_patch)`：`C ⊆ A × 𝔇_ρ` 为被引原因集合（动作维度与鲁棒性维度的叉积），`r ∈ 𝔏` 为自然语言理由，`π_patch` 为对边端计划 `P_e` 或证书 `J` 的补丁。LLM 提案 `E ~ LLM(ctx)`，其中 `ctx = (失败轨迹, G_S, ρ, 历史反事实)`。

**定义 122（(ε,δ,γ)-忠实性）**
给定模型 `M`、输入 `x`、结果 `y`。称 `E` 关于 `M` 是 `(ε,δ,γ)`-忠实的，当且仅当：
- **充分性**：`|M(x) − M(do(C = x_C))| ≤ ε`（只保留被引原因即可保持结果）；
- **必要性**：`∀ c ∉ C, |M(x) − M(do(c = x_c^base))| ≤ δ`（未引原因不得是隐藏主因）；
- **对比性**：`|M(do(C = x_C^alt)) − M(x)| ≥ γ`（翻转被引原因必须显著改变结果）。
记 `faith(E) = (1_{充分}, 1_{必要}, 1_{对比})`，并定义连续分数 `score_f = w_s(1−S) + w_n(1−N) + w_c·C` 供门控使用。

**定义 123（解释稳健性）**
`ρ_exp(E) = 1 − E_{δa∼B_∞(0,ε_a)}[ |C(a) Δ C(a+δa)| / |C(a) ∪ C(a+δa)| ]`。把 `ρ_exp` 作为鲁棒性谱的新维度 `d_exp`，要求 `ρ_exp ≥ ρ_min(exp)`。注意这是关于**归因**的稳定性，不是结果的稳定性，两者可分离。

**定义 124（语义-动作接地）**
设语义计划 `π_S` 的谓词集为 `P`，接地映射 `g: P → 2^{A×𝔇_ρ}`。要求：
- **soundness**：`∀p, g(p) ⊆ Sat(p)`（不把不满足谓词的动作说成满足）；
- **coverage**：`|dom(g)| / |P| ≥ θ_g`。
接地缺口 `G_gap = (1 − coverage) + soundness_violation_mass`；`G_gap > Θ_g` 的计划判为“悬空承诺”，拒绝部署。

**定义 125（LLM 提案-验证协议）**
`Verify(E) → (ok?, score_f, ρ_exp, G_gap, cost)`，包含三次干预实验、归因扰动采样与符号接地检查。只有 `Verify` 通过的解释可进入证书层；失败时把**反例**（被否证的因果方向、接地失败的谓词）回传给提案层，形成 `propose → verify → counterexample → repropose` 循环。

**定义 126（信任校准解释证书）**
`J_X = (E, score_f, ρ_exp, G_gap, ECE, evidence)`，其中 `ECE` 为 LLM 自报置信与验证通过率之间的期望校准误差。可部署当且仅当：
```
Verified(E) ∧ faithfulness ≥ φ_f ∧ ρ_exp ≥ ρ_min(exp) ∧ G_gap ≤ Θ_g ∧ ECE ≤ η
```
证书 `J_X` 与第 54 轮 `J` 联合，构成 `(ρ, A_cert, γ_ce, δ_a, E, score_f, ρ_exp, G_gap, ECE)`。

**定义 127（反事实解释记忆）**
`M_cf = {(x_i, C_i, π_patch_i, trust_i)}`，`trust_i` 随复验结果与分布漂移更新。检索 `R(M_cf, x)` 仅作为 LLM 提案上下文；**记忆条目不得直接作为证书证据**，防止“先污染记忆、再让 LLM 复述、最后被当成证据”的二次洗白链路。

## 2. 关键算法 伪代码

### IP-121 FEC（Faithful Explanation Certificate）

```python
def certify_explanation(E, M, x, eps, delta, gamma, phi_f):
    C = E.C
    # 充分性：只保留被引原因
    suff = abs(M(x) - M.do({c: x[c] for c in C}))
    # 必要性：逐个去掉未引原因
    nec = max([abs(M(x) - M.do({c: x_base[c]})) for c in universe(A) - C],
              default=0.0)
    # 对比性：翻转被引原因
    contr = abs(M.do({c: x_alt[c] for c in C}) - M(x))
    ok = (suff <= eps) and (nec <= delta) and (contr >= gamma)
    return ('ok' if ok else 'reject',
            dict(suff=suff, nec=nec, contrast=contr, score_f=score(suff,nec,contr)))
```

### IP-122 XGV（Semantic-Action Grounding Verifier）

```python
def ground_plan(pi_S, action_profiles, Sim):
    g, violations = {}, 0.0
    for p in pi_S.predicates:
        cands = {a for a in A if Sim.satisfies(p, a)}
        g[p] = cands
        # soundness：不得把不满足的动作用作证据
        if not cands <= Sat(p, action_profiles):
            violations += mass(cands - Sat(p, action_profiles))
    coverage = len(g) / max(1, len(pi_S.predicates))
    G_gap = (1 - coverage) + violations
    return ('ok' if G_gap <= THETA_G else 'reject', g, G_gap)
```

### IP-123 REX-LLM（Propose–Verify Reverse Explanation Loop）

```python
def rex_llm(failure, G_S, rho, memory, budgets):
    ctx = (failure, G_S, rho, retrieve(memory, failure))
    for t in range(MAX_ROUNDS):
        E = LLM.propose(ctx)                       # 只提案
        res = certify_explanation(E, failure.M, failure.x, *budgets.faith)
        if res.ok:
            gr = ground_plan(E.pi_patch, failure.skills, failure.Sim)
            if gr.ok:
                rho_exp = explanation_robustness(E, failure, budgets.eps_a)
                if rho_exp >= rho_min_exp:
                    return ('ok', J_X(E, res.score, rho_exp, gr.G_gap))
        ctx = ctx + (counterexample(res),)          # 反例回灌，推动再提案
    return ('abstain', 'no_faithful_explanation')    # 宁可弃答，不造假解释
```

### IP-124 ERS（Explanation Robustness Score）

```python
def explanation_robustness(E, failure, eps_a, n=64):
    C0, stable = set(E.C), 0.0
    for k in range(n):
        d = sample_linf_ball(eps_a, failure.A)
        Ct = set(LLM.repropose_same_ctx_with(failure.perturb(d)).C)
        stable += 1 - jaccard(C0, Ct)
    return stable / n
```

### IP-125 CAL（Calibration & Trust Gate）

```python
def trust_gate(J_X, eta, phi_f):
    return ('deploy' if J_X.verified and J_X.score_f >= phi_f
            and J_X.rho_exp >= rho_min_exp and J_X.G_gap <= THETA_G
            and J_X.ECE <= eta else 'quarantine')
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| FEC | O((\|A\|·\|𝔇_ρ\|)·T_sim) | O(\|C\|) | 干预可执行、反事实基线有效 |
| XGV | O(\|P\|·\|A\|) | O(\|P\|·\|A\|) | soundness 检查、无悬空谓词 |
| REX-LLM | O(R·(FEC+XGV+ERS)) | O(R·\|E\|) | 反例回灌、弃答优于造假 |
| ERS | O(n·\|A\|·T_LLM) | O(n·\|C\|) | 扰动分布与真实漂移同支撑 |
| CAL | O(1) per cert | O(1) | 校准集独立、ECE 有界 |

**命题（提案-验证分离引理）**
设验证器在真实边端上的假接受率为 `α_v`，即 `P(Verify(E)=ok ∧ E 不忠实) ≤ α_v`。则对**任意** LLM（包括被提示注入或对抗性幻觉的 LLM），进入部署的证书中不忠实解释的比例满足：
```
P(E in cert ∧ ¬faithful(E)) ≤ α_v / P(Verify(E)=ok)。
```
**含义**：解释的忠实性下界由验证器而非 LLM 决定；LLM 再能“讲故事”，也无法把不忠实解释抬进证书层，除非验证器本身在分布外失效。

**正确性定理（Faithful-Explainable Composition Soundness）**
承接第 54 轮 (A22)–(A28)，新增：**(A29)** 验证器的 do-干预在置信域 `D_conf` 内与真实边端一致（域内保真假设）；**(A30)** 接地图 `g` 经符号 + 仿真双重检查，悬空谓词被拒绝；**(A31)** 校准集独立同分布且 `ECE ≤ η`。则
```
P(deploy ok) ≥ 1 − Σ_d(1−ρ_min(d)) − β_E − P(δ_a>Θ_a) − P(¬faithful | Verified) − P(G_gap>Θ_g)
P(false-cert) ≤ P(x ∉ D_conf) + α_v + η
```
关键：**忠实性是可验证量**、**LLM 仅提案**、**记忆只提案不举证**、**域外一律弃答**。

## 4. 实验设计 E162–E166

| 实验 | 指标 | 目标 |
|---|---|---|
| E162 解释忠实度 | 充分/必要/对比三率 + score_f | 忠实率 ≥ 85% |
| E163 幻觉拒绝率 | 验证器假接受率 `α_v` | ≤ 2% |
| E164 解释稳健性 | `ρ_exp` 随动作扰动的衰减曲线 | 扰动 5% 时 ≥ 0.8 |
| E165 LLM 组合 vs propose-verify | 组合 soundness、负迁移率 | soundness +15%，负迁移 −30% |
| E166 校准与信任门控 | ECE、overtrust 事故数 | ECE ≤ 0.05，事故 −50% |

**消融**：去掉记忆（检验检索增益）、去掉 ERS（检验归因稳健性是否必要）、去掉接地（检验悬空谓词的代价）、把验证器换成 LLM 自评（检验 propose-verify 分离是否是主要收益来源）。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 验证器在域外假接受（faithwashing） | 高 | 暴露 `D_conf`、域外弃答、红队反事实、独立校准集 |
| LLM 被提示注入/轨迹污染 | 高 | 输入清洗、提案隔离、记忆降权、双验证器交叉 |
| 语义-动作接地图 soundness 不足 | 高 | 符号检查 + 仿真反例 + 接地缺口硬门控 |
| ERS 采样成本高 | 中 | 分层采样 + 早停 + 只对高风险证书算 |
| 解释记忆污染 | 中 | trust 衰减 + 定期复验 + 记忆不举证 |
| 弃答率过高影响可用性 | 中 | 主动采样补证据、分层置信域、人工兜底 |

## 6. 本轮最大风险

**一句话**：把 LLM 放在“提案者”位置、用干预验证器裁决，确实能让解释从“流畅”升级为“可证伪”，但整条链的 soundness 全押在**验证器置信域与真实边端的一致性**上——一旦仿真覆盖存在系统偏差，一个在偏差区“看似三重忠实”的解释会顺利通过验证，生成一份**洗白过的证书**，从而制造比无解释更危险的虚假信任，故必须把 `D_conf` 与证书一同暴露、域外一律降级为“未验证解释”、并用独立红队与在线漂移检测持续证伪验证器自身。

# 第 55 轮产物 · 创新点清单 v32：GroundEdge-Faith（FEC×XGV×REX-LLM×ERS×CAL×XCM）

> 承接第 54 轮产物 v31（GroundEdge-GenSim+++）。本轮在鲁棒性层 `𝕃` 与动作-协同层 `𝔸` 之上，新增 **解释层 `𝕏`**，把「可解释性 × 大语言模型」落成一套可验证架构：

### IP-123 REX-LLM

```python
def rex_llm(failure, G_S, rho, memory, budgets):
    ctx = (failure, G_S, rho, retrieve(memory, failure))   # 记忆只进上下文
    for _ in range(MAX_ROUNDS):
        E = LLM.propose(ctx)                                # 提案层
        vr = certify_explanation(E, failure.M, failure.x, *budgets.faith)
        if not vr.ok:
            ctx += (counterexample(vr),); continue
        gr = ground_plan(E.pi_patch, failure.skills, failure.Sim,
                         budgets.theta_g, budgets.theta_G)
        if not gr.ok:
            ctx += (counterexample(gr),); continue
        re = explanation_robustness(E, failure, budgets.eps_a)
        if re < rho_min_exp:
            ctx += (counterexample('unstable_attribution', re),); continue
        if not in_confidence_domain(failure, D_conf):       # 域外不举证
            return ('quarantine', 'out_of_D_conf')
        return ('ok', J_X(E, vr.score_f, re, gr.G_gap,
                          calibrate(failure), evidence(vr, gr, re)))
    return ('abstain', 'no_faithful_explanation')           # 宁弃答不造假
```

### IP-124 ERS

```python
def explanation_robustness(E, failure, eps_a, n=64):
    C0, acc = set(E.C), 0.0
    for _ in range(n):
        d  = sample_linf_ball(eps_a, failure.A)
        Ct = set(LLM.repropose_same_ctx(failure.perturb(d)).C)
        acc += 1 - jaccard(C0, Ct)
    return acc / n
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| FEC | O((\|A\|·\|𝔇ρ\|)·T_sim) | O(\|C\|) | 三性齐全、反事实基线有效 |
| XGV | O(\|P\|·\|A\|) | O(\|P\|·\|A\|) | sound 接地、悬空谓词拒绝 |
| REX-LLM | O(R·(FEC+XGV+ERS)) | O(R·\|E\|) | 反例回灌、弃答优于造假 |
| ERS | O(n·\|A\|·T_LLM) | O(n·\|C\|) | 扰动支撑匹配真实漂移 |
| CAL | O(1)/cert, O(N) 校准 | O(1) | 校准集独立、ECE 有界 |
| XCM | O(k·d) 检索 | O(\|M_cf\|) | 信任衰减、记忆不举证 |

**引理 1（提案-验证分离）**
若验证器假接受率 `P(Verify(E)=ok ∧ ¬faithful(E)) ≤ α_v`，则对任意 LLM（含提示注入/对抗幻觉），进入部署证书的不忠实比例为
```
P(¬faithful | in cert) ≤ α_v / P(Verify(E)=ok)。
```
即忠实性下界由验证器决定，与 LLM 能力无关；LLM 无法把不忠实解释“讲”进证书层。

**引理 2（接地缺口传播）**
若 `G_gap > Θ_g` 的计划被拒绝，则进入部署的每个语义谓词均存在 sound 动作支撑，且悬空承诺导致的负迁移满足 `P(neg-transfer) ≤ P(G_gap ≤ Θ_g ∧ soundness_violation)`。

**正确性定理（Faithful-Explainable Composition Soundness）**
承接第 54 轮 (A22)–(A28)，新增：
**(A29)** 验证器 do-干预在 `D_conf` 内与真实边端一致；**(A30)** 接地经符号+仿真双检；**(A31)** 校准集独立且 `ECE ≤ η`。
则：
```
P(deploy ok) ≥ 1 − Σ_d(1−ρ_min(d)) − β_E − P(δ_a>Θ_a)
                 − P(¬faithful | Verified) − P(G_gap>Θ_g)
P(false-cert) ≤ P(x ∉ D_conf) + α_v + η
```
关键：**忠实性可验证**、**LLM 仅提案**、**记忆不举证**、**域外弃答**。

| 实验 | 指标 | 目标 | 对照 |
|---|---|---|---|
| E162 解释忠实度 | S/N/C 三率、score_f | 忠实率 ≥ 85% | 纯 LLM 解释 vs FEC |

| E165 组合 soundness | 部署成功率、负迁移率 | +15% / −30% | 直接 LLM 组合 vs REX-LLM |
| E166 校准门控 | ECE、overtrust 事故 | ECE ≤ 0.05、事故 −50% | 无 CAL vs CAL |

**建议数据集/场景**：机械臂抓取-放置（动作维度可枚举）、移动操作（云边时延可注入）、对抗提示注入（测 `α_v`）、分布漂移回放（测 `D_conf` 与 ECE）。

**消融矩阵**：
1. 去记忆（XCM）→ 看提案命中率是否下降；
2. 去 ERS → 看跨场景解释是否失效；
3. 去接地（XGV）→ 看悬空谓词造成的负迁移；
4. 用 LLM 自评替代验证器 → 检验分离引理是否是主要收益来源；
5. 域外不弃答 → 量化 faithwashing 事故。

## 6. 本轮最大风险

**一句话**：LLM 提案 + 形式验证的分离架构能把解释从“流畅”升级为“可证伪”，但其 soundness 全押在**验证器置信域 `D_conf` 与真实边端的一致性**上——一旦仿真覆盖存在系统偏差，一个在偏差区“看似三重忠实”的解释会通过验证并生成**洗白证书**，制造比无解释更危险的虚假信任；因此必须把 `D_conf` 与证书同时暴露、域外一律降级为“未验证解释”，并以独立红队、在线漂移检测和验证器自身的周期性证伪来护栏。
