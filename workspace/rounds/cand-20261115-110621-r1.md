# 第 5 轮（灵感循环第 5 轮；本轮灵感：「伦理与合规」×「开源软件」）

> **基线**：第 4 轮 InstructGauge-WR（IP-328–333；定义 448–467；引理 59–62；实验 E457–E472）。第 3 轮 InstructGauge 的五不变式、CVC 闭环与严格退化链继续继承不变。
> 本轮纪律：**合规只增加「可检查的义务与证据」，不增加任何物理能力；开源只增加「可复现性与透明性」，不作为安全性的前提。** 两个新灵感各沿一条轴升级 WR v4，且任一环节不可用都必须逐级退回 WR v4 → InstructGauge v3 → ToolGauge，并把结果**显式标记为未审计**，而不是静默通过。

## 0. 直觉与动机

**灵感 1（伦理与合规 → 从「不出事」到「能问责」，是规范层而不是新传感器）**
直觉：工程师问「这个系统安全吗」和监管者问「如果出了问题，你能证明你按规则做了吗」是两个不同的问题。安全性关心**物理后果**，合规/伦理关心**可辩护性**：每条影响他人的动作都要能回答「谁授权、依据哪条规则、拿什么证据、在哪个版本上、失败了由谁负责」。因此伦理合规不是给机器人再加一个「道德传感器」，而是三件事的叠加：**(a) 规范层**——把义务 O（必须发生）、禁止 P（绝不能发生）、许可 F（默认拒绝，显式放开）与证据义务 E（义务的可失败证明）写成机器可判定的对象；**(b) 证据层**——每条义务绑定一个**能返回 fail** 的谓词，并携带来源与版本；**(c) 责任层**——动作到责任主体/角色的映射，以及不可逆动作的人工监督门。关键洞察是：**「没有证据」必须是一个不同于「满足」的第三态**。把「没查」当成「通过」，正是绝大多数合规失败的起点。

**灵感 2（开源软件 → 可复现的信任，但「很多人看」不是安全证明）**
直觉：开源给的不是「免费」，而是**可复现性与可追溯性**：软件物料清单（SBOM）让每个组件、版本、许可证、数据用途都可枚举；可复现构建让第三方能判断「我审计的就是你部署的」；独立复现让合规从「自我声明」变成「可反驳的公开证明」。但开源有两个反直觉的坑。第一，**Linus 定律不是安全定理**：暴露的组件同样暴露给攻击者，供应链投毒（恶意依赖、依赖混淆、被接管的维护者）会把不合规组件悄悄带进闭环。第二，**透明会放大「合规剧场」**：当账本、清单、证书都公开且可复现时，系统会获得一种「已经被独立审计过」的合法性外观——哪怕规范本身漏项、监控钩子覆盖不全。也就是说，开源提升的是**证据的可得性**，不是**义务被满足的程度**。

**灵感 3（两者耦合 → 把「可审计」与「合规」之间的三条缝隙显式建模）**
直觉：伦理合规定义「要证明什么」，开源定义「拿什么、以何种可复现的方式证明」。最危险的耦合不是一个组件坏了，而是**三者同时看起来正常**。于是本轮盯住三条缝隙：

1. **规范缺口（specification gap）**：规范本身不完整、彼此冲突或含无法判定的价值判断。此时监控不能「猜一个阈值」，而必须把该义务显式降级为 `UNVERIFIED` 并计入**合规欠账**。
2. **版本缝隙（TOCTOU）**：被审计的构建、被签发的证书、上机部署的构建可能不是同一个；离线审计全过，线上跑的却是另一个版本。解法是把审计结论绑定到 `(规则版本, 组件图 ρ, build_id, 账本区间)` 的哈希上，不一致即拒绝。
3. **披露缝隙（disclosure gap）**：为了可审计而公开原始感知数据，会直接违反隐私与知情同意义务。解法是最小披露：对外只发布证据的摘要与「谓词成立」的零知识证明，原始帧按 consent 标签与保留期限最小化留存。

解法不是「上一套合规模块」，而是四根结构支柱：**义务—证据对偶**（无证据即未验证）、**构建—部署绑定**（防 TOCTOU）、**许可—同意类型系统 + 最大合规子图**（保证可优雅退化）、**最小披露审计**（透明但不泄露），再叠加**价值分层不扩权**（伦理偏好只在可行集内重排序）。

## 1. 研究问题（本轮要回答什么）

- **Q1（规范可编译性）**：伦理/合规要求能否被编译成「可失败、可监控、可追溯」的运行时谓词，而不是被硬编码成一组拍脑袋阈值？当规范无法编译或自相冲突时，系统如何诚实地降级而不是伪装通过？
- **Q2（审计可复现性）**：如何保证「被审计的版本」与「部署的版本」是同一个，并让第三方在不接触敏感原始数据的前提下独立复现审计结论、甚至给出反例轨迹？
- **Q3（开放性的代价）**：开源 SBOM 与公开账本在提升透明度的同时，如何不泄露隐私、不扩大供应链攻击面、不把不合规依赖带进闭环？「透明度—隐私—安全」之间是否存在可量化的权衡前沿？

## 2. 四条设计原则（雏形，正式化见产物区定义 468–479）

**P1 义务—证据对偶（Obligation–Evidence Duality）**
每条义务 `o ∈ O` 必须绑定一条**能在轨迹上返回 fail** 的证据谓词 `e ∈ E`。`o` 只有在 `e` 返回 pass 且证据携带来源与版本时才算满足；否则一律记 `UNVERIFIED` 并计入合规欠账 `debt`。禁止「无证据的合规」。

**P2 构建—部署绑定（Build–Deploy Binding）**
任何审计结论只对四元组 `(N.ver, ρ, build_id, L[l..r])` 成立。部署侧在每次上电与热替换时重算组件图根哈希；与已审计清单不一致即拒绝执行并向账本写入不一致事件。这是对「审计的是一个版本、跑的是另一个版本」的结构性防御。

**P3 许可—同意类型系统与最大合规子图（License–Consent Typing & Maximal Compliant Subgraph）**
把组件图上的许可证兼容关系与数据同意标签做成偏序/格上的合成类型检查。若整图不可类型化，则导出**最大可类型化子图**作为回退目标——保证「不合规依赖」被切除后系统仍能运行，而不是整机停摆或整机带病运行。

**P4 价值分层不扩权（Lexicographic Non-Expansion）**
伦理偏好（隐私最小化、检查机会公平、可逆优先、人工可覆盖）以字典序 `≻_eth` 表达，但**只在同一物理可行集内重排序候选**，绝不扩大可行域。安全与法律硬约束永远支配价值偏好。

## 3. 与基线的接口（如何退化）

- 规范不可编译 / 义务冲突 / 证据谓词不可判定 ⇒ 停用该义务并标 `UNVERIFIED`、`debt++`；动作层退化为 WR v4，但**审计等级降级**，不得声称合规；
- 组件图不可类型化 / 根哈希不匹配 / 供应链可疑 ⇒ 切除不合规子图，回退到最大合规子图；子图为空 ⇒ WR v4；
- 账本或审计复现器失效 ⇒ 退回本地签名回执 + 事后离线审计，不阻断 50Hz 安全路径；
- 隐私/同意约束与感知需求冲突 ⇒ 关闭对应感知通道（如腕部相机），退化为 CVC 单帧漂移检测（继承引理 62）；
- 人工监督门不可用 ⇒ 不可逆/高风险动作强制 `K=1` 并阻塞，而非放行；
- 全部合规增强失效 ⇒ InstructGauge v3 → ToolGauge；所有产出统一标 `UNVERIFIED`。

## 4. 预期贡献

1. 一个**义务—证据对偶**的规范编译口径：把伦理/合规要求变成三值可判定对象，使「未验证」成为一等公民，从结构上消灭「默认通过」；
2. 一套**构建—部署绑定的防 TOCTOU 审计**：证书与账本只对具体 `build_id/ρ` 成立，哈希不符即拒绝，堵住「审计≠部署」这一最常见的形式合规漏洞；
3. 一个**许可—同意类型系统**与**最大合规子图**回退：使开放组件供应链的合规问题可局部切除、可优雅退化；
4. 一个**最小披露的第三方复现协议**：只发布摘要与零知识证据，让外部审计在不接触原始数据的情况下仍能重放并给出反例；
5. 一条完整可证伪路径：E473–E488 覆盖规范可靠性、TOCTOU 绑定、可复现审计、许可/同意合成、账本防篡改、隐私最小化、人工监督、供应链投毒、退化等价与 50Hz 时序保全。

## 5. 本轮最大风险

**一句话**：最大的风险是「合规剧场」——系统可以完全可复现、全程有账本、证书齐全，却因为**规范本身漏项**或**监控钩子覆盖不全**而在做不该做的事；开源与透明不会修正这个缺口，反而会把「可审计」误当成「已合规」，给错误行为镀上一层经得起复核的合法性外观。

## 2. 形式化定义（要点）

**定义 468（三值满足语义）** 对轨迹 `T = (s_0, a_0, ev_0, …, s_T)` 与规范 `N`：
```
sat(N, T) = VIOL         若 ∃p∈P, ∃t: p(a_t, s_t) = ⊤
          = SAT          若 ∀o∈O, 其证据谓词 e_o 在 T 上返回 pass 且证据带来源/版本
          = UNVERIFIED   其余情况
```
`UNVERIFIED` 既不等于通过也不等于违规；它触发 `debt++` 与审计等级降级。禁止把 `UNVERIFIED` 折叠成 `SAT`。

**定义 469（义务—证据对偶）** 规范可编译当且仅当
```
∀o ∈ O, ∃e_o ∈ E : e_o 在 T 上可判定 ∧ (¬e_o 时存在可执行的反例见证)
```
证据 `ev = (digest, source, time, build_id)`；`o` 满足要求 `e_o = pass` 且 `build_id` 与当前部署一致。

**定义 470（组件图与构建—部署绑定）** 组件图 `ρ` 为有向图，边表示「由…构建/依赖/派生」。定义审计等价：
```
Audited(ρ_pub) ≡ Deployed(ρ_dep)
  ⟺ h(build_id_pub) = h(build_id_dep) ∧ h(root(ρ_pub)) = h(root(ρ_dep))
```
不等价即拒绝执行并写账本 `INCONSISTENT_BUILD`。这把审计结论从「抽象版本」钉到「具体构建」。

**定义 471（许可—同意类型系统）** 合成判定：
```
Γ ⊢_ρ π : τ     （组件组合 π 在许可/同意上下文 Γ 下设类型 τ）
κ₁ ⊓ κ₂ = κ₁ ∩ κ₂        （同意取交集：更严格者胜）
lic₁ ⊑_lic lic₂          （义务更少者兼容义务更多者）
```
若 `ρ` 不可类型化，定义最大合规子图：
```
MaxCompliantSubgraph(ρ) = argmax_{ρ' ⊆ ρ, ρ' 可类型化} |ρ'|   （按能力覆盖加权）
```
由引理 65，其存在且对子图封闭，故可作退化目标。

**定义 472（合规账本）** 第 `t` 条记录与链：
```
r_t = h( r_{t-1} ‖ chunk_id_t ‖ N.ver_t ‖ digest(ev_t) ‖ acct(a_t) ‖ build_id_t )
L   = (r_0, …, r_T),  r_0 = genesis
```
`L` 防篡改：修改任一中段记录将使其后所有 `r` 失配。

**定义 473（合规监控与截断）** 监控器在块 `C=(a_1…a_K)` 上增量求值：
- 若某 `a_t` 触发 `P` ⇒ 立即 `VIOL`，截断到违规前前缀 `C_{1:t-1}`（沿用第 3 轮前缀封闭）；
- 若某 `o` 的证据谓词返回 `UNVERIFIED` ⇒ `debt++`，按策略阻塞或降级但不谎报通过；
- 若某 `a_t` 不可逆 ⇒ 进入定义 476 的监督门。

**定义 474（伦理偏好字典序）**
```
safety ≻_legal legal ≻_eth privacy ≻_eth reversibility ≻_eth efficiency
```
偏好只作用于可行候选集 `A_feas` 上的排序：`rank_eth: A_feas → A_feas` 为置换，**不改变 `A_feas` 的成员**。因此不扩权。

**定义 475（最小披露审计）** 对外仅发布 `redact(ev) = (digest, zk-proof[e 成立])`；复现器：
```
AuditReplay(ρ, L, N, {digest, zk}) → PASS | FAIL(counterexample) | INSUFFICIENT_EVIDENCE
```
`FAIL` 必须附反例轨迹索引；`INSUFFICIENT_EVIDENCE` 对应 `UNVERIFIED`，不得升级为 `PASS`。

**定义 476（人工监督门）** 对不可逆/高风险动作集合 `A_irr`，执行前要求：
```
Gate_irr(a) = sig_human( chunk_id ‖ N.ver ‖ build_id ‖ r_{t-1} )
```
缺失签名 ⇒ 该动作强制 `K=1` 且阻塞，或回退到可逆替代动作；签名本身入账本以形成责任链。

## 3. 关键算法骨架

```python
# IP-334 NormCompiler
class NormCompiler:
    def compile(self, norm):
        monitors, obligations = [], []
        for p in norm.P: monitors.append(self._compile_prohibition(p))
        for o in norm.O:
            try:
                e = self._compile_evidence(o)
                obligations.append((o, e))
            except Uncompilable:
                obligations.append((o, UNVERIFIED))   # 显式降级，绝不默认通过
        return CompiledNorm(monitors=monitors, obligations=obligations)

    def violates(self, a, s):
        return any(m(a, s) for m in self.monitors)

# IP-335 PManifest
class PManifest:
    def build(self, components):
        nodes = {c.id: dict(h=hash_of(c), ver=c.ver, lic=c.lic, kappa=c.kappa) for c in components}
        edges = [(c.id, d.id) for c in components for d in c.deps]
        build_id = hash_of(sorted(nodes.items()) + sorted(edges))
        return ComponentGraph(nodes, edges, root_hash=hash_of(build_id), build_id=build_id)

    def verify_deploy(self, rho_pub, rho_dep):
        return hash_of(rho_pub.build_id) == hash_of(rho_dep.build_id) and \
               rho_pub.root_hash == rho_dep.root_hash

# IP-337 ComplianceLedger
class ComplianceLedger:
    def append(self, chunk_id, norm_ver, ev_digest, acct, build_id):
        prev = self.head.hash if self.head else GENESIS
        r = hash_of(prev, chunk_id, norm_ver, ev_digest, acct, build_id)
        self.records.append(Record(r, prev, chunk_id, norm_ver, ev_digest, acct, build_id))
        return r

    def verify(self):
        prev = GENESIS
        for rec in self.records:
            if rec.prev != prev or rec.hash != hash_of(prev, rec.chunk_id, rec.norm_ver,
                                                        rec.ev_digest, rec.acct, rec.build_id):
                return False, rec.index
            prev = rec.hash
        return True, None

# IP-338 AuditReplay（最小披露）
class AuditReplay:
    def replay(self, rho, ledger, norm, published):
        if not self.manifest.verify_deploy(rho, published.rho):
            return Verdict.INSUFFICIENT_EVIDENCE("build mismatch")
        for o, e in norm.obligations:
            if e is UNVERIFIED:
                return Verdict.INSUFFICIENT_EVIDENCE(o)
            if not zk_verify(published.proof[o], e):
                return Verdict.FAIL(counterexample=published.index[o])
        ok, _ = ledger.verify()
        return Verdict.PASS if ok else Verdict.FAIL("ledger tampered")
```

## 4. 推导

**引理 63（监控可靠性 / Soundness）** 若 `NormCompiler` 对禁止集 `P` 的编译是可靠的（每个监控谓词 `m_p` 满足 `m_p(a,s)=⊤ ⇒ p(a,s)=⊤`），且执行钩子覆盖全部 `a_t`，则任何被执行的动作都不违反 `P`；即监控器是 `P` 的运行时强制。证：若 `p(a_t,s_t)` 成立，则 `m_p(a_t,s_t)` 成立，监控在 `apply` 前截断，矛盾。该引理只保证**相对于已编码的 P** 的可靠性，不保证 P 覆盖全部伦理要求——这正是引理 69 与最大风险的来源。

**引理 64（构建—部署绑定的防 TOCTOU 性）** 在哈希抗碰撞假设下，若部署构建与已审计构建不同（`root(ρ_dep) ≠ root(ρ_pub)` 或 `build_id` 不同），则 `verify_deploy` 以 `1−negl(λ)` 概率拒绝。证：不同构建映射到同一根哈希即构成碰撞；`build_id` 由规范化源码与依赖树决定，任何依赖替换都改变根。故「审计≠部署」被结构性检测。

**引理 65（许可—同意合成的单调性）** 若 `ρ` 在上下文 `Γ` 下可类型化，则任意子图 `ρ' ⊆ ρ` 亦可类型化；且 `MaxCompliantSubgraph(ρ)` 存在、对 `ρ` 的能力覆盖在包含关系下单调。证：类型推导只使用各组件局部许可与边上的兼容约束，删除节点/边不会引入新的违反；故类型化对子图封闭，有限图中取能力覆盖最大者即得退化目标。该单调性保证「切除不合规依赖」不会把系统切成不可运行。

**引理 66（账本防篡改）** 在哈希抗碰撞与 `r_0` 已锚定的前提下，篡改任一记录 `r_i` 必导致链在 `i+1` 处失配，`verify()` 返回 `(False, i+1)`。证：`r_{i+1}` 以 `r_i` 为输入，逐项哈希；单点修改无法保持后继一致。

**引理 67（伦理偏好不扩权）** `EthicalPref.rank` 是 `A_feas` 上的置换，`Im(rank) = A_feas`，故可行域与能力闭包不变；伦理偏好只改变选择顺序，不改变可执行集合。证：`sorted` 不增删元素。

**引理 68（最小披露审计的可靠性）** 若零知识证明系统可靠且摘要绑定证据内容，则 `AuditReplay` 返回 `PASS` 蕴含 `SAT`（相对于已发布证据与规范）；返回 `FAIL` 时附可检验反例；证据不足时返回 `INSUFFICIENT_EVIDENCE` 而绝不 `PASS`。证：`PASS` 需通过全部 `e_o` 的 `zk_verify` 与账本校验，任一不满足即落入 `FAIL` 或 `INSUFFICIENT_EVIDENCE`。

**引理 69（退化等价性 + 诚实的未验证）** 关闭全部合规增强（NormCompiler / PManifest / LicenseConsent-TS / Ledger / AuditReplay / Gate）后，执行动作序列与 WR v4 逐步相同；差异仅在于所有产出被打 `UNVERIFIED` 且 `debt` 不被清零。证：合规层只做前置拒绝/截断与后置记录，移除后控制流退化为 `instructgauge_wr`；标签变化不改变动作。

## 8. 本轮最大风险

**一句话**：最大的风险是**规范缺口导致的「合规剧场」**——账本可复现、清单可追溯、审计可独立重放，但若 `N` 漏掉某条真正重要的义务、或监控钩子未覆盖某条执行路径，系统仍会以「证书齐全」的姿态做出不合规的动作；开源透明不仅无法修复这一缺口，还会把「可审计」误当作「已合规」而放大风险。次级风险是「透明—隐私—安全」三难：为可审计而公开清单/账本，可能泄露敏感数据或扩大供应链攻击面，缓解手段（最小披露 + 依赖签名 + 最大合规子图）会牺牲部分开放性与性能。
