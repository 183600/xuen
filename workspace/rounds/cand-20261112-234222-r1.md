# 第 3 轮迭代（灵感循环 v3：「需求洞察」×「6D位姿估计」）—— 把评分器当用户：需求编译的位姿谓词

> 承接 v2（UIP-01′~15：Gazebo × 实时性 × 模块化）。本轮不是再加一个模块，而是**换问题定义**：先反演“评分器到底要什么”，再决定“6D 位姿该估什么、估到多准、何时估”。核心主张：**32 个任务的 94 个计分步都可以写成有序的位姿/关节/接触谓词；把 6D 位姿估计限制在“需求位姿商”上，并用机器人自身的 EE 位姿 + 腕部运动做近场多视，可以用更少的感知、更少的数据、更低的延迟，直接对上评分口径。**

---

## 0. 直觉：三个反常识

1. **比赛的“用户”是评分器，不是演示视频。** 需求洞察在别的产品里是访谈用户；在这里，用户是一个极其挑剔但可读的评分器：它把需求写在 `scoring_points`、`generalization.human_*` 和权重里。公开演示回答的是“动作长什么样”，评分器回答的是“哪些空间关系成立、按什么顺序成立”。两者不是同一个分布。
2. **6D 位姿不是估得越全越好，而是估得越“对需求”越好。** 评分谓词只关心少数实体之间的相对位姿与关节状态：杯把-挂钩、插头-插口、碗-碗、拉链头-拉链。对“不改变任何谓词”的对称/不可观测自由度取商，估计目标从完整 `SE(3)` 变成**需求位姿商**；条件数更好，精度预算也能按谓词边界分配。
3. **没有物体位姿标签，不等于没有免费标尺。** 接口给了 `left/right_ee_pose_gripper_base`、夹爪开度、关节状态和腕部 RGB；机器人自己的运动就是一条已知基线的多视图系统。**关节编码器就是第二台相机**：腕部单目在近场可通过已知 EE 位移做三角化，拿到毫米级深度，而不需要外部 6D 位姿大模型。

**需求洞察的三层**（本轮的工作定义）：

- **显式需求**：`info.json.score_steps` 的 94 个步骤与权重（官方文本）。
- **隐式需求**：`generalization` 里的未见物品（23/32 个任务）与人为干扰（30/32 个任务）；它们不是“附加噪声”，而是评分的另一条主轴。
- **未言明需求**：评分器的容差、对称性、接触判据、步骤依赖关系。它们没有写在文本里，只能通过成功演示的一致性校验 + 真机分数反演。

**两条本轮最强的推论：**

- **R3（需求-演示错位）**：演示数据覆盖的是“成功执行”的外观分布，评分器要的是“谓词在容差内成立”；因此**按演示频率训练/采集会系统性低估细接触与恢复**。需求洞察的产物应是一张**可执行的谓词账本**，而不是更大的视频数据集。
- **R4（位姿精度不是全局标量）**：头部双目在 0.6 m 只有厘米级；腕部本体多视在 0.15 m 可到亚毫米。**精度应按谓词边界分配**：粗放置用头部双目，细接触用腕部主动多视；用一个全局“6D 位姿精度”指标会既浪费又不够。

## 2. 严谨定义

### 2.1 需求契约（Requirement Contract）

**直觉**：把评分器当成一个用户，把它的需求写成一份可执行的合同：每一步要什么、按什么顺序、容差多少、哪些自由度无所谓。

**定义**：任务 \(\tau\) 的需求契约
\[
\mathcal C_\tau=(S_\tau,E_\tau,\{(\phi_j,w_j,\delta_j,G_j,\kappa_j)\}_{j=1}^{n_\tau},\mathcal H_\tau)
\]
其中 \(S_\tau\) 是计分步，\(n_\tau\le5\)；\(E_\tau\) 是依赖边（\(i\to j\) 表示 \(j\) 以 \(i\) 为前提）；\(\phi_j:\mathcal X\to\{0,1\}\) 是计分谓词；\(w_j\) 是权重，\(\sum_j w_j=100\)；\(\delta_j\) 是容差；\(G_j\subseteq SE(3)\) 是保持 \(\phi_j\) 不变的对称/规范群；\(\kappa_j\) 是判定该谓词所需的观测/关键点；\(\mathcal H_\tau\) 是人为干扰事件集合。一个 episode 的步骤分代理为
\[
\hat s_\tau(X)=\sum_{j=1}^{n_\tau} w_j\,\phi_j(X)\quad\text{s.t. 若 } i\to j \text{ 且 }\phi_i=0,\text{ 则 }\phi_j=0.
\]
**依赖闭包**：当检测到 \(\phi_i\) 从 1 变 0，所有 \(i\) 的后继都必须失效并重做；这比“只重做当前步”更符合有序计分。

### 2.2 需求位姿商（Requirement Pose Quotient）

**直觉**：碗绕竖直轴转多少度不影响“叠上去”；插头的滚转却影响卡扣方向。需求决定了哪些位姿自由度是“真的”，哪些是规范自由度。

**定义**：设世界状态 \(X=(T_{o_1},\dots,T_{o_m},q,g)\)，其中 \(T_o\in SE(3)\)、\(q\) 是关节角、\(g\) 是夹爪。定义
\[
X\sim_\tau X'\iff \phi_j(X)=\phi_j(X')\ \forall j.
\]
商空间 \(\mathcal X/{\sim_\tau}\) 是评分的**最小充分状态**。对物体 \(o\)，其需求稳定子
\[
G_o^\tau=\{h\in SE(3):\phi_j(T_o h,X_{-o})=\phi_j(T_o,X_{-o})\ \forall j,X_{-o}\}.
\]
估计目标不是 \(T_o\)，而是 \(T_o G_o^\tau\in SE(3)/G_o^\tau\)。例：碗/盘绕竖直轴 \(SO(2)\) 是规范群（5 DOF）；杯把定义了偏航，规范群更小；网线插头的滚转影响卡扣，通常不可商掉；毛巾是形变体，用折线/角点而非刚体位姿。

### 2.3 分数敏感精度（Score-Sensitive Accuracy）

**直觉**：谓词离边界很远时，位姿估粗一点也不会改分；离边界很近时，估得再准也可能翻。精度应由“离边界多远”决定。

**定义**：设 \(g_j(X)\) 是谓词 \(\phi_j\) 的有符号 margin（在达成域内为正），\(L_j\) 是 \(g_j\) 对位姿误差的 Lipschitz 常数。若位姿误差 \(\|\delta\xi\|<g_j(X)/L_j\)，则 \(\phi_j\) 不可能翻转。于是第 \(j\) 步的**必要精度**为
\[
\epsilon_j^*(X)=\frac{g_j(X)}{L_j}.
\]
验证器的位姿不确定度 \(\Sigma_\xi\) 只需在边界附近满足 \(n^\top\Sigma_\xi n\le(\epsilon_j^*)^2\)。这给出一个**按谓词分配的精度预算**，而不是全局毫米级目标。

### 2.4 相对位姿图与全局规范自由度

**直觉**：评分器从不问“物体在世界坐标系的绝对位姿”，只问“插头相对插口在哪、碗相对碗在哪”。绝对坐标系是多余的。

**定义**：需求涉及的实体构成图 \(G=(V,E)\)，边 \(e=(u,v)\) 带相对变换 \(T_{uv}=T_u^{-1}T_v\)。所有谓词只依赖 \(\{T_{uv}\}_{e\in E}\)。对全体实体左乘同一刚体变换 \(H\) 不改变任何 \(T_{uv}\)，因此存在 6 维全局规范自由度；若只估相对图，可完全去掉它。所需位姿自由度约为 \(6|E|-\sum_o\dim G_o^\tau-6\)，通常远小于 \(6|V|\)。

### 2.5 干扰 = 谓词翻转 + 位姿差分

**直觉**：人把杯子向后推、把拉链拉开、把叠好的毛巾翻开，表面上动作不同，本质都是“某个已经为真的谓词变假”。

**定义**：设 \(p_t=(\phi_1(X_t),\dots,\phi_n(X_t))\)。称 \(t\) 时刻发生**需求撤回**，若存在 \(j\) 使 \(p_{t-1,j}=1,p_{t,j}=0\)。用机器人自身动作模型预测 \(\hat p_t^{\text{own}}\)，定义干扰残差
\[
r_t=p_t-\hat p_t^{\text{own}}.
\]
若 \(r_{t,j}=-1\) 且超过噪声门限，则判为**外部干扰**而非自身动作失败；若 \(r_t\approx0\) 但仍失败，则是策略执行失败。这个区分决定了“重做”还是“改策略”。

### 2.6 本体多视三角化

**直觉**：腕部相机没有深度，但机器人知道自己的手在哪儿；手一动，单目就变成多目。

**定义**：腕部相机在 base 系的位姿 \(T_w(t)=T_{\text{base}}^{ee}(t)\,T_{ee}^{cam}\)，其中 \(T_{\text{base}}^{ee}(t)\) 由接口的 EE 位姿给出，\(T_{ee}^{cam}\) 是手眼外参。对同一物点 \(P\) 在两时刻的像素 \(u_t,u_{t'}\)，用射线三角化得 \(\hat P\)。深度误差近似
\[
\sigma_Z\approx\frac{Z^2\sigma_d}{f\,b_{\text{eff}}},
\]
其中 \(b_{\text{eff}}\) 是两时刻相机中心的有效基线。手眼外参可离线标定，或用已知 EE 运动 + 静态场景特征做 AX=XB 自标定；公制尺度由关节编码器保证。

## 3. 瓶颈假设（v3）

- **H1（最高杠杆）**：评分器的需求是稀疏谓词，而公开数据是成功外观分布；**按谓词覆盖率而不是 episode 数来选数据/造数据**，能在细接触与恢复轴上获得更大边际收益。
- **H2**：完整 6D 位姿是过参数化且病态的；**需求位姿商**在对称/遮挡/未见物体下更可辨识，且估计误差中不影响谓词的成分不应计入。
- **H3**：头部双目在桌面距离只有厘米级，无法单独支撑插入/拧动/拉链的容差；**腕部本体多视**能在近场补到亚毫米，且不需要外部 6D 位姿模型。
- **H4**：人为干扰的通用表示是**谓词翻转**；位姿差分 + 自身动作反事实比外观差异更早、更稳地检测“进度被撤回”。
- **H5**：主动感知应按**谓词 margin 与不确定度**分配，而不是固定帧率/固定块长；这同时降低延迟与无效动作。

## 5. 本轮最大风险

**一句话**：最大的风险是把我们自写的需求契约误当成官方评分器——如果隐藏评分用的谓词、容差或顺序与我们的假设不同，整套位姿谓词会在一个错误目标上高度自洽；必须用公开成功演示做契约一致性校验，并把真机分数作为唯一终审。

**→ 本轮最值得押注：UIP-16（需求契约）× UIP-17/18（需求位姿商 + 本体多视）× UIP-01″/09″（谓词验证 + 撤回恢复）组成的“需求驱动的位姿谓词闭环”**——它把 v2 的“扰动恢复”从外观启发式升级为可计算的空间谓词，并且完全落在选手 API 与离线算力之内。

## 1. 旗舰深潜：UIP-01″ · RPPV（Requirement-Predicate Progress Verifier）

### 1.1 机制

动作块 \(A=(a_1,\dots,a_{T_a})\) 不整段盲执行。在每个块边界（或每 \(k\) 步），用 **需求位姿图** 估计谓词向量
\[
p_t=(\phi_1(X_t),\dots,\phi_n(X_t)),
\]
并把每个谓词的状态分为 `done / ongoing / regressed / fail / blocked`。其中：

- `regressed`：上一时刻为真、当前为假，且位姿差分超过噪声门限（UIP-19）。
- `blocked`：前置依赖未满足，当前谓词不可达（例如盖子没打开就倒药）。
- 当检测到 `regressed` 于第 \(i\) 步，**失效 \(i\) 及其所有后继**（依赖闭包），把当前目标回退到 \(i\)；而不是只重做“当前步”。

### 1.2 与 v2 的差异

| 维度 | v2 UIP-01′ | v3 UIP-01″ |
|---|---|---|
| 验证信号 | 视觉/语言规则或 VLM | **位姿谓词**：相对变换、关节角、接触/插入深度 |
| 撤回定义 | 时序差分/视觉判据 | **谓词从真变假 + 自身动作反事实** |
| 重做范围 | 当前子目标 | **依赖闭包**（后续步骤一并失效） |
| 精度分配 | 全局阈值 | **按谓词 margin 分配**（分数敏感精度） |
| 块长 | 按任务阶段 | 按 **margin/不确定度**（UIP-13） |
| 合规风险 | 外部 VLM 可能算“多模型” | 规则库 + 共享骨干谓词头，无外部大模型 |

### 1.3 伪代码

```python
class RPPV:
    """UIP-01″；与 UIP-13/15/17/18/19 组合。"""
    def reset(self):
        self.policy.reset()
        self.p = [0] * self.n              # 谓词真值向量
        self.g = 0                          # 最早未完成的计分步
        self.redo = 0
        self.buf = []

    def get_action(self, obs):
        if not self.buf:
            X = self.perceive(obs)          # UIP-17/18：需求位姿图
            p, margin, sigma = self.contract.eval(X)
            self.update_progress(p, margin, sigma)
            k = self.schedule(margin, sigma)  # UIP-13
            self.buf = list(self.policy.get_action(obs, self.g, k))[:k]
        return self.buf.pop(0)

    def update_progress(self, p, margin, sigma):
        for j in range(self.n):
            if self.p[j] == 1 and p[j] == 0:
                external = self.detector.is_external(j, sigma)  # UIP-19
                self.invalidate_closure(j)                      # 依赖闭包
                self.g = min(self.g, j)
                self.redo += 1 if external else 0
            self.p[j] = p[j]
        while self.g < self.n and self.p[self.g] == 1:
            self.g += 1

    def schedule(self, margin, sigma):
        if any(m < 2 * s for m, s in zip(margin, sigma)):
            return 1                       # 边界/接触：高频重观测
        if all(m > 5 * s for m, s in zip(margin, sigma)):
            return self.K_MAX              # 远离边界：大块执行
        return self.K_MID
```

### 1.4 可行性、资源、落地

- **可行性高**：所有量都在选手 API 内；`observation.language` + `obs` 的 EE 位姿/夹爪/图像足以构造相对位姿图。
- **资源**：离线标注 32 个契约；一个共享骨干的关键点/谓词头；一张推理卡；无额外接口。
- **落地**：① 先做 UIP-16 的需求契约；② 选 5 个代表任务（T01 挂杯、T14 倒药、T19 拉链、T26 插网线、T27 叠碗）打通位姿图；③ 接入依赖闭包与重做；④ 用 UIP-11 的同一谓词库在 Gazebo 回放调参；⑤ 真机校准。
- **风险**：谓词误判导致反复重做 → UIP-15 的置信度门限/最大重做次数/延迟预算；谓词契约错 → 见 §11。

## 2. UIP-16 · RCE（Requirement Contract Extraction）

### 2.1 流程（离线，可无人值守 + 人工复核）

1. **读官方需求**：解析 `tasks_v2/<slug>/info.json` 的 `zh/en_desc`、`score_steps`、`generalization`、权重。
2. **实体与关系抽取**：把每一步映射到实体（物体、容器、工具、夹爪）和关系（抓/放/插入/套叠/开合/旋转/倒/吸/折叠）。
3. **谓词化**：写成 `grasp / place / insert / articulate / fold / fluid / orient / sort` 的谓词，附容差 \(\delta_j\)、对称群 \(G_j\)、关键点 \(\kappa_j\)。
4. **依赖图**：从步骤顺序与物理前提构造 \(E_\tau\)（例如“盖盖子”以“装入”为前提，“拉链”以“对齐”为前提）。
5. **演示一致性校验**：在公开成功演示上回放，检查每个 episode 结束时 \(\phi_j\) 是否按预期为真；若某谓词从未为真或从不翻转，视为契约错误并修正。
6. **数据覆盖审计**：按谓词统计公开数据的覆盖，输出缺口（尤其 `human_*` 与细接触）。

> 产物是**规则库**（JSON/代码），不是第二个学习模型；部署时只保留一个共享骨干的谓词/关键点头。离线阶段可用任意工具（含 LLM）辅助起草，但必须人工复核并用演示校验。

## 3. UIP-17 · RPQ（Requirement Pose Quotient）

### 3.1 机制

对每个任务实体，根据需求契约确定：

1. **必须估的自由度**：谓词实际依赖的相对位姿分量。
2. **规范/对称自由度** \(G_o^\tau\)：不改变任何谓词的分量，直接商掉。
3. **可观测关键点** \(\kappa_j\)：用少量语义关键点构造需求坐标系，而不是估完整物体网格。

例：

| 对象/任务 | 需求关心的量 | 可商掉的自由度 | 估计目标 |
|---|---|---|---|
| 碗/盘（叠放、入架） | 中心位置、竖直轴、支撑面高度 | 绕竖直轴偏航（多数情况） | 5 DOF 需求位姿 + 关键点 |
| 杯（挂杯架） | 杯把中心、杯轴、挂钩相对位置 | 杯身纹理/绕轴无把手部分 | 杯把关键点 + 杯轴 |
| 插头/插口（T10/T26） | 连接器尖端、插入轴、滚转（卡扣） | 线缆柔性形变 | 尖端 + 轴 + 卡扣方向 |
| 拉链（T19/T23/T31） | 拉链头位置、拉链缝方向 | 包体外观 | 拉链头 + 缝线方向 |
| 毛巾（T16） | 角点、折线、层间关系 | 刚体全局位姿 | 关键点/折线（非刚体） |
| 药瓶（T14） | 瓶盖旋转角、瓶口位置、倾角 | 瓶身纹理 | 瓶盖角 + 瓶口 + 轴 |

### 3.2 实现

- **共享骨干**：关键点热图头 + 相对位姿回归头，与策略共享视觉-语言编码器；满足“单模型”合规。
- **经典几何优先**：头部双目三角化、PnP、点云配准；能不学的就不学。
- **不确定性**：每个关键点输出协方差；用 Jacobian 传播到谓词 margin，驱动 UIP-20 的主动感知。
- **对称处理**：若谓词依赖某个规范自由度（例如杯把必须朝外），该自由度不被商掉；契约按任务显式声明，而不是全局假设。

### 3.3 谓词评估伪代码

```python
def eval_predicate(phi, X, contract_j):
    # X: 相对位姿图 + 关节角 + 夹爪
    g = contract_j.signed_margin(X)          # 有符号 margin
    sigma = contract_j.propagate_sigma(X)    # 位姿/关键点不确定度
    truth = g >= 0
    near = abs(g) < 2 * sigma
    return truth, g, sigma, near
```

### 3.4 为什么不是“完整 6D 位姿”

- 完整 \(SE(3)\) 在对称/遮挡/透明/形变物体上病态；需求商只保留可辨识、且影响分数的分量。
- 绝对位姿需要全局坐标系；相对位姿图只估边，天然对桌子位置/背景变化鲁棒。
- 关键点比网格更容易从少量演示/合成数据学习；不需要每个物体都有 CAD。

## 4. UIP-18 · PMP（Proprioceptive Multi-view Sparse Pose）

### 4.1 机制

接口的 EE 位姿给出了腕部相机在 base 系的运动（差一个手眼外参）。当腕部相机移动时，同一物点在不同时刻的像素构成多视图；用已知的相机中心位移做三角化，得到近场度量深度。**机器人关节编码器提供了公制尺度，腕部单目因此不再是“无尺度单目”。**

- **粗定位**：头部双目（已校正）→ 全局、米制、厘米级。
- **细定位**：腕部彩色 + 已知 EE 位移 → 局部、亚毫米级。
- **融合**：因子图/卡尔曼滤波，按源协方差加权；头部给先验，腕部给局部精化。
- **手眼**：离线标定（标定板）或在线 AX=XB（已知 EE 运动 + 静态场景特征）；标定误差直接进入 \(\Sigma_\xi\)。

### 4.2 误差预算（本轮复算）

**头部双目**（\(f_x\approx228.5\) px，基线 \(b\approx61.4\) mm）：

| Z (m) | 视差 (px) | 1 px 误差 (mm) | 0.5 px 误差 (mm) | 0.1 px 误差 (mm) |
|---:|---:|---:|---:|---:|
| 0.3 | 46.8 | 6.4 | 3.2 | 0.6 |
| 0.5 | 28.1 | 17.8 | 8.9 | 1.8 |
| 0.6 | 23.4 | 25.6 | 12.8 | 2.6 |
| 0.8 | 17.6 | 45.6 | 22.8 | 4.6 |
| 1.0 | 14.0 | 71.2 | 35.6 | 7.1 |

**腕部本体多视**（\(f\approx435\) px，有效基线 \(b_{\text{eff}}\)，流误差 \(\sigma_d\)）：

| \(b_{\text{eff}}\) (mm) | Z (m) | 0.5 px 误差 (mm) | 1 px 误差 (mm) |
|---:|---:|---:|---:|
| 30 | 0.10 | 0.38 | 0.77 |
| 30 | 0.15 | 0.86 | 1.72 |
| 30 | 0.30 | 3.45 | 6.90 |
| 50 | 0.10 | 0.23 | 0.46 |
| 50 | 0.15 | 0.52 | 1.03 |
| 50 | 0.30 | 2.07 | 4.14 |
| 80 | 0.15 | 0.32 | 0.65 |
| 80 | 0.30 | 1.29 | 2.59 |

**读法**：头部双目在 0.6 m 即使 0.1 px 也只有 2.6 mm，刚好卡在插入容差边缘；腕部在 0.15 m、50 mm 基线、0.5 px 可达 0.5 mm。**这就是“按谓词分配传感器”的物理依据**：粗放置用头，细接触用腕。

### 4.3 伪代码

```python
def perceive(obs, contract, hand_eye, buffer):
    X = {}
    # 1) head stereo: metric, global prior
    for e in contract.edges:
        kp = detect_keypoints(e, obs.head_left, obs.head_right)
        X[e] = triangulate_stereo(kp, obs.head_params)
    # 2) wrist proprioceptive multi-view: fine, local
    for e in contract.near_edges:
        kp = detect_keypoints(e, obs.wrist_left)  # or right
        T_w = obs.ee_pose @ hand_eye
        X[e] = fuse(X[e], triangulate_proprioceptive(kp, T_w, buffer))
    return X
```

### 4.4 风险

- 手眼外参误差会系统性偏置近场深度 → 用标定板/在线自标定 + 不确定度传播；关键任务保留头部双目交叉校验。
- 腕部移动时物体也可能被手带着动 → 只在准静态段/接近段做多视；或把物体关键点与夹爪相对位姿一起估计。
- 遮挡/透明/反光 → 用接触/关节状态兜底；谓词契约允许 `blocked` 状态。

## 5. UIP-19 · PDD（Pose-Delta Disturbance Detection）

### 5.1 事件模型

把 `human_*` 的文本统一成可检测事件：

| `human_*` 文本型 | 形式化 | 检测量 | 恢复动作 |
|---|---|---|---|
| 平移/旋转已就位物体（“杯子向后”“水果向右”“锁向左”） | 谓词实体位姿跳变，\(\phi_j:1\to0\) | 相对位姿差分 + 谓词翻转 | 重新抓取/重新放置 |
| 反向关节（“拧回”“拉开”“翻开”“打开”） | 关节角/接触状态翻转 | 关节角/关键点变化 | 反向操作恢复 |
| 拿走/移除（“中途把锁拿走”“叠第二后拿下第二”） | 实体缺失 | 关键点丢失/位姿外推失败 | 搜索/重新获取 |
| 放回起点（“放回传送带起点”） | 位置谓词翻转 | 位姿跳变 | 重新分拣 |

### 5.2 自身动作反事实

仅看“谓词变假”会把自身执行失败误判为外部干扰。用自身动作预测 \(\hat p_t^{\text{own}}\)（由当前 chunk + 位姿图预测），定义
\[
r_t=p_t-\hat p_t^{\text{own}}.
\]
- \(r_{t,j}=-1\)：自身动作预测应保持为真，但实际变假 → **外部干扰**。
- \(r_{t,j}\approx0\) 且仍失败 → **自身执行失败**（改策略/重试）。
- \(r_{t,j}=+1\)：意外达成（可接受，但记录）。

### 5.3 伪代码

```python
def detect(p_prev, p_now, p_own, sigma, contract):
    events = []
    for j in range(contract.n):
        flipped = (p_prev[j] == 1 and p_now[j] == 0)
        if not flipped:
            continue
        residual = p_now[j] - p_own[j]
        if residual == -1 and contract.margin_moved(j) > 3 * sigma[j]:
            events.append(("external", j))
        else:
            events.append(("own_failure", j))
    return events
```

### 5.4 延迟与误报

- 位姿差分只需在块边界计算，延迟远低于重新跑 VLM。
- 用 margin + 不确定度做门限，避免边界抖动触发误重做；连续两次翻转才升级为外部干扰。
- 与 UIP-15 的“最大重做次数/延迟预算”联动。

## 6. UIP-20 · RCAS（Requirement-Coverage Active Sensing）

### 6.1 机制

不是“每帧都估位姿”，而是**只在谓词边界附近花感知/动作预算**：

| 谓词状态 | 感知动作 | 目的 |
|---|---|---|
| margin 大、远离边界 | 不重估，继续执行大块动作 | 省延迟 |
| margin 小、接近边界 | 触发腕部近场多视/小幅移动增加视差 | 降不确定度 |
| 关键点被遮挡 | 手腕转动/换视角/轻触 | 解除遮挡 |
| 对称歧义 | 主动旋转已知角度或移动基线 | 消解规范自由度 |
| 谓词翻转 | 停止当前块，进入 UIP-19/09″ | 恢复 |

### 6.2 需求覆盖

定义数据/采集的覆盖优先级：
\[
\text{priority}_j \propto w_j\cdot\frac{\partial \phi_j}{\partial \xi}\cdot\big(1-\text{coverage}_j\big),
\]
即“权重大、对位姿敏感、当前数据没覆盖”的谓词优先。`human_*` 与细接触谓词的 coverage 最低，优先用 UIP-12 造数据，而不是盲目扩大演示数量。

### 6.3 与 UIP-12/11 的关系

- **UIP-16** 产出谓词与干扰类型；
- **UIP-12** 按谓词/干扰类型在 Gazebo 生成“干扰→恢复”数据；
- **UIP-11** 用同一谓词库给 Gazebo rollout 打分；
- **UIP-20** 用真实部署中的 margin/覆盖缺口决定下一步采什么数据。

## 7. 端到端算法（组合视图）

```python
class RequirementDrivenPolicy:
    def __init__(self, backbone, contract, hand_eye, governor):
        self.policy = backbone
        self.contract = contract          # UIP-16
        self.hand_eye = hand_eye
        self.governor = governor          # UIP-15
        self.verifier = RPPV(...)         # UIP-01″
        self.detector = PDD(...)          # UIP-19
        self.sensor = PMP(...)            # UIP-18

    def reset(self):
        self.verifier.reset()
        self.buffer = []

    def get_action(self, obs):
        X = self.sensor.perceive(obs, self.contract, self.hand_eye, self.buffer)
        p, margin, sigma = self.contract.eval(X)       # UIP-17
        self.verifier.update_progress(p, margin, sigma)
        k = self.verifier.schedule(margin, sigma)      # UIP-13
        self.buffer = list(self.policy.get_action(obs, self.verifier.g, k))[:k]
        return self.buffer.pop(0)
```

## 9. 合规与风险

- **单模型合规**：UIP-16 是**规则库**，不是第二个大模型；关键点/谓词头与策略共享骨干。避免把 FoundationPose/SAM-6D 等外部 6D 模型作为独立服务接入（可能被判“多模型”且增加延迟）。
- **代理错配**：需求契约是**假设**，不是官方评分器；必须用公开成功演示做一致性校验，并用真机分数做终审。若契约与官方不一致，优先修契约，而不是在错误目标上继续优化。
- **传感器现实**：API 只给腕部彩色，没有腕部深度；手眼外参需标定；透明/反光/形变物体需接触/关节状态兜底。
- **接口红线**：`obs_delta_indices` 只声明必要键；`action_chunk_size` 与返回形状严格按 README；块边界重规划不要造成统计异常。
- **数据空白**：公开数据无物体位姿/网格标签、无 `human_*` 演示；用 Gazebo + 脚本化干扰（UIP-12）补，但需真机锚点防“仿真过拟合”。

## 11. 本轮最大风险 & 押注

**一句话**：最大的风险是把我们自写的需求契约误当成官方评分器——如果隐藏评分用的谓词、容差或顺序与我们的假设不同，整套位姿谓词会在一个错误目标上高度自洽；必须用公开成功演示做契约一致性校验，并把真机分数作为唯一终审。

**→ 押注：UIP-16（需求契约）× UIP-17/18（需求位姿商 + 本体多视）× UIP-01″/09″（谓词验证 + 撤回恢复）**——把“扰动恢复”从外观启发式升级为可计算的空间谓词，并用机器人自身运动补上缺失的深度；这是当前规则已写明、公开数据全空白、且完全落在选手 API 权限内的最大得分缺口。
