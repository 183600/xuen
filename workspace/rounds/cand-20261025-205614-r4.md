# 第 8 轮（本循环第 4 轮）· CR-G4P：抓取为放置服务，场景图做共享状态，基准测试定位断链

> 检索/复核日期：**2026-10-25（UTC）**。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「抓取规划」「场景理解」「基准测试」。我先做了一次对账，纠正上一轮两个会影响全盘判断的误读：**排名不是“成功率与步骤分综合排序”，而是先按 32 任务总平均成功率排序，成功率相同才看总平均步骤分；公开榜单至今仍是占位数据。** 然后我把三个词各自钉到可核实的事实上，得到本轮主判断：**成功率是一条乘法链；官方 320 trials 无法告诉我们链断在哪；因此先把“抓取-放置”当成一个联合决策变量（G4P），用任务条件化的度量语义场景图（SGM）提供共享几何，用链式基准（CSP）定位最弱条件成功率。** 这不是推翻第 7 轮，而是把“终局放置优先”修正为“抓取为放置服务、按链诊断”。

## 0. 先对账：六件会改变判断的事实

### 0.1 排名是字典序：成功率第一，步骤分只做 tie-break

官方手册原文（[S1]）：

> 实时榜单按 32 个任务的 **总平均成功率** 进行排序，成功率相同时按 **总平均步骤分** 排序，若仍相同，则提交日期较早的模型排序靠前。

这句话把第 7 轮的核心假设改掉了一半：

- **终局放置仍然是成功闸门**：32/32 任务的 episode 成功都要求所有评分步骤完成，终局步骤权重合计 1275/3200 = **39.8%**。
- **但步骤分不是排名主目标**：它只在成功率同分时起作用。为了步骤分牺牲成功率，是负期望。
- **首步也不是配角**：首步权重合计 1135/3200 = **35.5%**，16/32 任务的首步是抓取类动作。抓取失败会直接截断整条链，后面权重再高也拿不到。
- 因此正确的研究目标不是“攻终局放置”，而是：**先最大化总平均成功率，再用步骤级诊断决定资源投向抓取、放置还是中间步骤。**

### 0.2 10 次/任务 = 5 轴 × 2 次，共 320 trials：官方协议没有轴级分辨力

官方手册（[S1]）：

- 每个任务 10 次独立运行；
- 5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰）各出现 **2 次**；
- 单次真机最长 180 秒，超时记失败；
- 全模型必须完成 32 个任务，不能混用多个模型。

算术上，p≈0.3 时：

| 样本量 | 用途 | 标准误 SE | 95% CI 半宽 |
|---:|---|---:|---:|
| 320 | 总平均成功率 | 2.56pp | ±5.0pp |
| 64 | 单轴（32 任务 × 2） | 5.73pp | ±11.2pp |
| 10 | 单任务 | 14.5pp | ±28.4pp |
| 2 | 单任务单轴 | 32.4pp | ±63.5pp |

两个独立模型差值的 SE≈3.6pp；80% power 下，双侧 α=0.05 的最小可检测效应约 **10pp**。这意味着：

- 官方 320 trials 适合最终排名，**不适合模型选择、消融和轴级归因**；
- 每任务每轴 2 次，几乎不能说明“某轴更弱”；
- 想检测 3–5pp 的真实提升，必须用**配对场景 + 分层部分池化 + 序贯检验**的内部基准，把方差压下来，再用少量官方调试槽校准。

### 0.3 榜单仍是占位，但头部模型族是真实存在的

`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`；8 个模型 × 32 任务的 256 条 `task_metrics` 是脚本生成；`runs.html` 是 256/256 占位；详情页明确写“测试视频占位”（[S4][S5]）。所以：

- **29.7%、28.5%、27.9% 这些数字不是真实成绩，不能用来判断谁强谁弱，也不能用来做轴级瓶颈推理。**
- 但占位榜里的模型名对应真实模型族，可以分析公开技术路线：MolmoAct2、WALL-OSS-0.5、DreamZero、GigaBrain-0、π0.5、GR00T N1.5；Spirit-v1.5 / DM0 公开资料不足，暂不分析。
- 这些模型族的共同点比排名更有信息量：**语义泛化已经很强，但物理链执行、传感器错配、持久记忆、抓放解耦和评测噪声仍是共同短板。**

### 0.4 Dex1-1 是平行夹爪，抓取空间被几何硬约束

Dex1-1 的公开参数（[S9]）：**90mm 行程、80mm 爪长、5–120N 夹持力、0.1mm 分辨率**。这带来三个直接约束：

1. **小/薄物体**（电池、网线、卡片、试管）需要边缘抓、捏取或侧向抓；张得太大或太深都会失败。
2. **大物体**需要 power grasp；但爪长只有 80mm，抓取中心必须落在物体可夹持截面上。
3. **插入类任务**（插头、网线、试管）要求夹持姿态不能挡住插入轴；一个“抓得稳”的抓取，可能因为腕部姿态受限而“放不进去”。

所以“抓得稳”不等于“抓得能放”。这正是 G4P 的物理基础。

### 0.5 33k 演示、4 相机、立体头，但 API 没有 depth

数据集（[S7][S8]）：

- 32 个数据集，**33,276 episodes、18.28M frames、169h、811GB**；
- LeRobot v3.0、30fps、4 路 640×480；
- 相机键为 `head_stereo_left/right` + `wrist_left/right`；
- 含双臂关节、EE 位姿（base/torso 两套）、夹爪、lower body；
- Apache-2.0；HangCup 实测 1,043 episodes / 194,564 frames，`lastModified` 2026-10-14；
- 每任务 `meta/tasks.parquet` 有 5 条英文复述（`@` 分隔）。

提交接口 v2（[S6]）只给 4 路 RGB，**没有 depth**；观测键是 `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`。数据集的高位相机叫 `head_stereo_left/right`，API 叫 `cam_left_high/cam_right_high`——命名不同，**很可能是同一对双目，但必须用标定板/官方确认**。

这给了“场景理解”一个非常具体的接口机会：

- 若两路高位相机是已标定双目：推理时可用立体匹配恢复**度量深度**，直接补上 API 缺失的 depth；训练时用数据集里的双目做同分布监督。
- 若不是：退化为单目深度，把深度头蒸馏进**唯一 checkpoint**，不调用外部模型；或者用桌面平面 + 已知物体模板做几何拟合。
- 无论哪条路，**不能让“训练用 RGBD、推理只有 RGB”的传感器错配悄悄吃掉精度**。这是头部模型族的一个共同风险，也是我们可以工程化吃掉的优势。

### 0.6 评分步骤：首步 35.5%，终局 39.8%，成功是乘法链

32 个任务的 `score_steps` 全部公开，每个任务满分 100（[S3]）。聚合：

- 首步权重 1135/3200 = **35.5%**；16/32 首步是抓取类。
- 终局步权重 1275/3200 = **39.8%**；按终局文本粗分类，28/32 终局是放置/插入/堆叠/闭合/整理类，4 个是拔出/取出/翻转/倾倒类（T05/T11/T12/T14）。
- 成功 = 所有步骤完成；步骤分 = 各步边际完成率的加权和。
- **步骤分不是条件成功率**：一个步骤可能“大多数 episode 都能到达”，但“到达后经常失败”；也可能“很早失败，导致后面根本没机会”。只看边际分，会把这两种情况混在一起。

这就是为什么需要一个**链式诊断**：估计每个任务每一步的条件成功率 \(R_{t,k}=P(\text{step }k\text{ succeeds}\mid\text{reached }k)\)，而不是只看终局权重或总步骤分。

## 1. 三个灵感词，各自钉到事实上

### 1.1 抓取规划：从“抓取成功”到“抓取-放置联合可行”

现有 VLA 的抓取大多是隐式的：策略直接输出末端动作，抓取质量只在“提起来”这一下被间接检验。抓取专项的证据则指向另一件事：

- **Execution-Aware Pre-Execution Ranking**（[S16]）把抓取候选按“下游放置执行是否可行”排序，联合选择达到 85.63%，固定目标 79.84%，并迁移到 xArm7。核心不是抓取分类器，而是**抓取条件化的放置可行性**。
- **Grasp-Dependent Feasibility Prediction**（[S17]）用无物理的 IK/碰撞标签学习“这个抓取能否把物体放到目标”，先排序再规划。
- **Pick and Place Planning is Better than Pick Planning then Place Planning**（[S19]）从规划角度证明：抓取与放置分开优化会丢掉联合可行性。
- **Grasp-Then-Plan with Failure Attribution**（[S18]）进一步把失败归因到抓取阶段还是放置阶段，支持“早重抓”而不是“到终局才失败”。

映射到 UniBot：

- 33k 演示里有大量“成功抓取 + 成功释放”的配对，可以挖出**抓取模式库**和**释放位姿库**；
- Dex1 的 90mm/80mm 几何给出硬过滤条件；
- 32 任务里有叠碗、插排、网线、试管、挂杯等不同“抓取-放置”耦合结构；
- 双臂任务还多一个“哪只手抓什么”的分配问题。

所以本轮把抓取规划升级为 **G4P（Grasp-for-Place）**：候选生成时就用下游放置可行性打分，抓取后若实际物体位姿不利，**在运输前重抓**，而不是等到终局才失败。

### 1.2 场景理解：不是通用 3D 重建，而是任务条件化的度量-语义图

场景图/场景记忆在 2026 年已经不是新概念：

- **Scene Graphs for Robotic Imitation Learning**（[S20]）把场景图作为时空上下文，提升模仿学习的长程一致性；
- **SOMA**（[S21]）用空间记忆处理“物体移出视野”后的操作；
- **OCC4M**（[S22]）用物体中心 4D 记忆做长程时空推理；
- **GeoMem-VLA**（[S23]）把 3D 场景理解内化为时序记忆；
- **MomaGraph**（[S24]）把场景图用于移动操作的任务与运动规划。

但 UniBot 不需要通用 SLAM，也不需要重建整个房间。它需要一张**任务条件化的桌面度量-语义图**：

- 节点：目标物体、容器、支撑面、槽位/挂点、左右夹爪、人手/干扰物；
- 边：`on`、`in`、`near`、`left_of`、`front_of`、`contains`、`occludes`、`aligned_with`；
- 属性：6D 位姿、包围盒、抓取亲和性（可夹宽度、爪长、接近方向）、容器开口/内部尺寸、槽位位姿、置信度、可动/透明/铰接；
- 记忆：跨 episode 保留；遮挡时保留最后位姿 + 不确定性；人手移动物体后做差分更新；重新出现时重定位。

这张图同时服务四件事：

1. **任务 grounding**：把“把黄色积木放到最左边”映射到物体节点和槽位边；
2. **抓取候选**：在物体节点上生成/过滤抓取；
3. **放置候选**：在容器节点上枚举槽位，检查 `in/on` 关系和碰撞；
4. **谓词验证与恢复**：用图关系判断步骤是否完成；人手干扰后，图差分触发重规划。

它不是“又一个规划器”，而是把第 7 轮的 SSG/PGL/OPT/SVL 串起来的**共享状态总线**。没有它，抓取规划和放置规划各自维护一套几何，必然在遮挡和干扰下失配。

### 1.3 基准测试：不是刷榜，而是用统计上有效的诊断找最弱链

基准方法学的 2026 年证据很一致：

- **What Are We Actually Benchmarking in Robot Manipulation?**（[S25]）指出 LIBERO/CALVIN 等基准存在 shortcut solvability、统计显著性不足、creeping overfitting、data-source dependence；只有约 19.8%/19.7% 的 SOTA 声明在统计上显著。
- **Beyond Binary Success**（[S26]）用序贯检验/SAVI 做样本高效、统计严格的策略比较。
- **ATOM-Bench**（[S27]）、**EBench**（[S28]）、**PhAIL**（[S29]）、**UMI-Bench**（[S30]）分别从原子技能、元素诊断、分布化评测、可复现真机评测推进。

UniBot 的官方协议恰好是“低样本、高噪声、成功优先”。如果我们直接拿官方 320 trials 做模型选择，就会：

- 把 ±5pp 的噪声当成真实差异；
- 在 2 次/轴的条件下误判“哪个泛化轴更弱”；
- 为了步骤分优化，反而牺牲成功率。

所以本轮把第 7 轮的 TCLB 升级为 **CSP（Chain-Step Profiler）**：

- 估计每任务每步的条件成功率，而不是只看总分；
- 用分层部分池化借跨任务/跨轴信息，避免每格 2 次的噪声；
- 用配对场景（同一初始场景，只切换一个因素）做 A/B；
- 用序贯检验/贝叶斯决策决定“继续跑还是停”；
- 用信息增益分配稀缺的真机调试槽。

CSP 不是提交给官方的第二个模型，而是**我们自己的选型与诊断工具**。它的产出是“链断在哪、置信度多少、下一批试验打哪里”，直接决定 G4P/SGM 的迭代方向。

### 1.4 为什么不是另外三条路

- **更大的 VLA / 世界模型**：DreamZero 已经 14B、7Hz，自部署成本和延迟都很现实；而且语义泛化不是当前唯一瓶颈。我们不需要再训一个更大的通才，只需要在 6B 底座上补几何和链式决策。
- **纯数据缩放**：33k 演示已经不小；导航数据缩放的旁证是“多样性 > 数量”[S33]。再堆同分布演示，边际收益低；外部数据又受规则限制。数据要做的是“抓取/释放模式 + 扰动场景”，不是盲目加条数。
- **纯 test-time search / 世界模型选 chunk**：DREAM-Chunk 这类方法有价值，但 14B 世界模型 + 多候选 rollout 的算力/延迟与 180s 赛制不匹配；它可以作为可选增强，不应是主线。
- **纯 benchmark**：CSP 本身不提高分数，只告诉你钱丢在哪。它是选型工具，不是参赛模型。

所以本轮选择 **G4P 作为最小直接攻击链的押注**，SGM 和 CSP 是它的两个使能器：一个给共享几何，一个给诊断。

## 2. 头部模型族的做法与共同瓶颈（基于公开路线，不基于占位榜）

> 再次强调：占位榜数字不可用。下面分析的是模型族的公开技术路线，以及它们在 UniBot 接口下**可能**遇到的瓶颈；不是对真实排名的解释。

| 模型族 | 公开路线（摘要） | 可能优势 | 在 UniBot 的可能瓶颈 |
|---|---|---|---|
| **MolmoAct2** | 动作推理模型；VLM + flow-matching action expert；强调自适应深度/空间推理（[S10]） | 语义-空间 grounding 强；适合语言条件任务 | API 无 depth；若依赖单目深度，接触级精度和延迟是风险 |
| **WALL-OSS-0.5** | 4B 部署型 VLA；面向真实机器人落地（[S11]） | 小、快、易自部署 | 容量有限；缺少显式抓取-放置几何推理时，长尾接触易丢 |
| **DreamZero** | 14B world action model；零样本策略；约 7Hz（[S12]） | 物理/环境泛化强；可作为世界模型 | 14B 自部署成本高；7Hz 对 30Hz 控制需 chunk/插值；精确接触是风险 |
| **GigaBrain-0** | 世界模型生成数据 + RGBD + CoT 的 VLA（[S13]） | 数据引擎强；空间理解好 | 若训练依赖 RGBD，API 只有 RGB 会有传感器错配；合成数据有 sim-to-real gap |
| **π0.5** | 异构数据 co-training + 高层子任务预测；开放世界泛化（[S14]） | 语义泛化、长程任务分解强 | 论文自述部分可观测与上下文/记忆限制；接触级精度不是主卖点 |
| **GR00T N1.5** | VLM + flow-matching action transformer + FLARE 世界建模；3B（[S15]） | 语言 grounding、跨本体泛化强 | 公开报告强调泛化/语言跟随，未主张接触级精度；新物体/新场景仍有 gap |
| **Spirit-v1.5 / DM0** | 公开技术报告不足 | 未知 | 不作推断 |

共同瓶颈可以归纳为五条（第 5 条是赛制/评测外部瓶颈）：

1. **语义泛化 ≠ 物理链执行。** 模型知道“把碗叠起来”，不等于能在 90mm 爪、80mm 爪长、碗沿间隙和遮挡下稳定完成。成功率是乘法链，任何一步的接触失败都会清零。
2. **RGBD 训练 → RGB 推理的传感器错配。** 多个强模型族在训练/研究中用 depth 或 RGBD，但 UniBot API 只给 RGB。谁先把 depth 补回来（立体/蒸馏/几何先验），谁就少一个隐藏 domain gap。
3. **反应式策略缺持久场景记忆。** 人手把物体移出视野、或把已叠好的碗拿走，反应式策略没有“刚才发生了什么”的状态，容易重复动作或找不到目标。
4. **抓取与放置分开优化。** 抓取质量头只看“提起来”，放置策略只看“放下去”；中间的夹持姿态、腕部可达性、物体-容器间隙没有联合约束，导致“抓成功、放失败”。
5. **评测噪声大，容易追噪声。** 320 trials、2 次/轴，真实提升 3–5pp 很可能被淹没；没有配对内部基准，团队会把随机波动当成方法有效。

这五条正好对应本轮三个组件：CSP 解决 5，SGM 解决 2/3，G4P 解决 1/4。

## 3. 本轮主判断：CR-G4P

### 3.1 形式化：成功率是条件成功率的乘积

对任务 \(t\)，设步骤 \(k=1,\dots,K_t\)，\(X_{t,k}\in\{0,1\}\) 表示第 \(k\) 步完成，episode 成功要求所有步骤完成：

\[
P(S_t=1)=\prod_{k=1}^{K_t} R_{t,k},\qquad
R_{t,k}=P(X_{t,k}=1\mid X_{t,1:k-1}=1).
\]

官方排名先最大化 \(\frac{1}{32}\sum_t P(S_t=1)\)，步骤分只在同分时比较。步骤分是 \(\sum_k w_{t,k}P(X_{t,k}=1)\)，它是**边际**完成率，不是 \(R_{t,k}\)。因此：

- 只看终局权重，会忽略“早段抓取失败”的截断效应；
- 只看总步骤分，会把“到达率低”和“到达后失败率高”混在一起；
- 正确的诊断目标是 **\(R_{t,k}\) 的链式剖面**，以及“提升哪个 \(R_{t,k}\) 对总成功率的边际收益最大”。

### 3.2 三个组件

```text
CSP（Chain-Step Profiler）
  测：每任务每步条件成功率 + 不确定性 + 下一批试验
        │
        ▼
SGM（Scene Graph Memory）
  看：物体/容器/槽位/夹爪/人手的度量-语义图 + 跨时记忆
        │
        ▼
G4P（Grasp-for-Place）
  做：抓取候选 × 放置候选联合排序；抓取前排除“能抓不能放”
        │
        ▼
单一 VLA checkpoint（WLA/GPR-VLA）
  执行：场景图 token + 步骤上下文 + 抓取/放置锚点 → action chunk
```

- **CSP 是“测量仪”**：没有它，不知道钱丢在哪一步，也不知道改进是否真实。
- **SGM 是“共享状态”**：没有它，抓取和放置各自估计几何，遮挡/干扰下失配。
- **G4P 是“决策器”**：没有它，抓取和放置分开优化，链式成功率上不去。

### 3.3 为什么是现在

- 33k 演示足够挖出抓取模式与释放位姿，不需要从零训练一个抓取模型；
- Dex1 的几何参数公开，候选过滤可以很硬；
- 数据集有双目高位相机，API 也可能有同一对双目，深度缺口有解；
- 场景图/记忆和抓取-放置联合规划都有 2026 年的直接证据，不需要赌一个未验证的方向；
- 基准方法学已经给出配对、序贯、部分池化的成熟工具，CSP 可以轻量实现。

### 3.4 预期收益与证伪条件

不承诺“+10pp”。在成功率优先、320 trials、p≈0.3 的赛制下，现实目标是：

- **总平均成功率 +3–5pp**（相对基线），且步骤级诊断能解释增益来自哪条链；
- 在配对内部基准上，G4P 相对“抓取-only 排序”的 top-1 放置可行性显著更高；
- 在 2–3 个调试槽任务上，终局步条件成功率提升，且无回归。

证伪条件：

- 离线/真机上 G4P 的 top-1 候选不优于 grasp-only，→ 砍掉 G4P，退回 SSG+SVL；
- SGM 的物体/容器位姿误差 >1cm/5°，→ 该任务退出图规划，回退 VLA；
- 双目不可用且单目深度蒸馏不达标，→ 关掉深度分支，只用平面/模板几何；
- CSP 预测的链式剖面与调试槽结果显著不符，→ 重新校准谓词与分层模型，不拿它做模型选择。

## 5. 风险与合规（先立后破）

- **单模型边界**：唯一学习模型是 VLA checkpoint；SGM/G4P 的学习头（抓取质量、放置可行性、步骤谓词、图编码、深度蒸馏）都在同一 checkpoint 内；候选采样、IK、碰撞、图更新、CSP 都是确定性代码。推理期不调用 SAM/FoundationPose/外部深度模型。
- **外部数据**：官方手册 2.3 之后未读到；L2L 自采数据默认 OFF，邮件 `challenge_support@unitree.com` 确认后再开。
- **双目假设**：`cam_left_high/cam_right_high` 与 `head_stereo_left/right` 是否同一对、是否已标定，未核实；先用标定板验证，失败则回退单目蒸馏/平面几何。
- **感知误差**：透明/反光/小件（试管、网线、电池）位姿估计易错；SGM 保留不确定性，低于阈值时回退 VLA，不硬用图规划。
- **G4P 组合爆炸**：候选数要限；抓取模式库先验 + 几何硬过滤 + GPU 批量 IK；规划器 1–5Hz，不阻塞 30Hz 策略。
- **基准噪声**：CSP 只用于内部选型；正式排名仍以官方 320 trials 为准；预注册指标，避免追噪声。
- **sim-to-real**：局部回放/合成只做负样本和课程，不主导训练；GF 软权重 + 真实混采。

## 1. 事实核对（本轮新增/修正；来源表见 §12）

### 1.1 排名规则：字典序，不是加权综合

官方手册原文（[S1]）：

> 实时榜单按 32 个任务的 **总平均成功率** 进行排序，成功率相同时按 **总平均步骤分** 排序，若仍相同，则提交日期较早的模型排序靠前。

中英手册对照见 [S1][S2]。推论：

1. 成功率的边际价值远高于步骤分；不能为了步骤分牺牲成功率。
2. 终局步是成功闸门（32/32 任务要求全步骤完成），但“闸门”不等于“唯一瓶颈”。
3. 步骤分是同分时的次级指标，也是**诊断信号**：它告诉我们哪些步骤的边际完成率低，但不能直接告诉条件成功率。
4. 提交日期是第三排序键；在成功率/步骤分接近时，早提交有微弱优势，但不值得为此提前提交未验证模型。

### 1.2 评测协议与统计功效

官方协议（[S1]）：

- 32 个任务，每任务 10 次独立运行；
- 5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰）各 2 次；
- 单次最长 180 秒，超时记失败，并按执行情况计算步骤分；
- 全模型必须完成 32 任务，不得混用多个模型；模型类型不限（World Model、VLA 均可）；
- 选手自部署，官方远程 API 调用；平台不托管模型。

统计功效（p≈0.3 仅作量级假设，二项分布近似；真实 p 不同则 SE 随之变化）：

| 样本量 | 估计对象 | SE | 95% CI 半宽 |
|---:|---|---:|---:|
| 320 | 总平均成功率 | 2.56pp | ±5.0pp |
| 64 | 单轴（32×2） | 5.73pp | ±11.2pp |
| 10 | 单任务 | 14.5pp | ±28.4pp |
| 2 | 单任务单轴 | 32.4pp | ±63.5pp |

两个独立模型差值的 SE≈3.6pp；80% power、双侧 α=0.05 的 MDE≈10pp。配对设计（同一场景跑 A/B）可把差值方差降到 \(\sqrt{2\sigma^2(1-\rho)/n}\)；若 \(\rho=0.5\)，MDE≈7pp；若 \(\rho=0.8\)，MDE≈4.5pp。

**结论**：官方 320 trials 适合最终排名，不适合模型选择、消融、轴级归因。内部必须用配对、分层、部分池化、序贯检验；官方调试槽只做校准与发布门。

### 1.4 Dex1-1 几何：抓取空间被硬约束

Dex1-1 公开参数（[S9]）：

| 参数 | 值 | 对抓取规划的含义 |
|---|---:|---|
| 行程 | 90mm | 物体可夹宽度必须 <90mm；大物体需要选可夹截面 |
| 爪长 | 80mm | 抓取深度受限；薄/高物体要避免爪尖碰撞 |
| 夹持力 | 5–120N | 易碎物需力控；重物需足够摩擦/包络 |
| 分辨率 | 0.1mm | 可以精细闭合，但依赖视觉/触觉估计 |
| 负载 | 20kg 形封闭 / 5kg 摩擦 | 抓取模式要匹配负载与加速度 |

任务里有电池、网线、卡片、试管等小/薄物体，也有碗、盘子、工具箱等大物体。**同一套抓取先验不能覆盖所有物体**，必须分桶：边缘/捏取、侧向抓、power grasp、双手协同。旁证：DemoGrasp 在 110 个未见物体上达到 86.5%，但小/薄物体只有 71.1% [S32]；杂乱场景抓取基准也显示遮挡/堆叠会显著改变难度 [S34]。这与 Dex1 的几何约束一致：小件仍是抓取泛化的硬点。

### 1.7 评分步骤：首步 35.5%，终局 39.8%

**注意**：这些权重是步骤分的权重，不是成功率的权重。成功率的每一步是等权的“与”门；步骤分只是同分时的次级排序。不要用步骤分权重去替代链式成功率。

## 2. 问题形式化：成功率是乘法链

### 2.1 链式成功

对任务 \(t\)，步骤 \(k=1,\dots,K_t\)，令 \(X_{t,k}\in\{0,1\}\) 表示第 \(k\) 步完成。官方成功要求所有步骤完成：

\[
S_t=\prod_{k=1}^{K_t}X_{t,k},\qquad
P(S_t=1)=\prod_{k=1}^{K_t}R_{t,k},
\]

其中

\[
R_{t,k}=P(X_{t,k}=1\mid X_{t,1}=1,\dots,X_{t,k-1}=1).
\]

\(R_{t,k}\) 是**条件成功率**；它才是链式诊断的目标。

### 2.2 步骤分是边际，不是条件

步骤分：

\[
\text{StepScore}_t=\sum_{k=1}^{K_t}w_{t,k}\,P(X_{t,k}=1),\qquad \sum_k w_{t,k}=100.
\]

\(P(X_{t,k}=1)\) 是边际完成率，混合了“到达该步的概率”和“到达后成功的概率”：

\[
P(X_{t,k}=1)=P(\text{reach }k)\cdot R_{t,k}.
\]

所以：

- 一个高权重终局步，如果到达率很低，边际分也会低；
- 一个低权重首步，如果条件成功率很低，会截断整条链，实际影响可能更大；
- 只看步骤分，无法区分“到不了”和“到了做不成”。

### 2.3 为什么终局不是唯一瓶颈

终局步是成功闸门，但链的乘积意味着**任何一步的 \(R_{t,k}\) 都可能成为最弱链**。特别是：

- 16/32 任务首步是抓取；抓取失败直接清零；
- 小/薄物体（电池、网线、卡片、试管）对平行夹爪不友好；
- 插入/挂杯/叠碗的失败可能发生在中途姿态，而不是最后释放；
- 人为干扰可能在任意步骤撤销已完成状态（官方备注里有“叠了第二个之后拿下第二个”“拉上拉链之后拉开”等）。

因此正确的问题是：**对每个任务，哪一步的 \(R_{t,k}\) 最低、提升它的边际收益最大、用什么干预能提升？** 这就是 CSP + G4P 的分工。

### 2.4 统计设计：为什么必须配对/分层/序贯

官方每任务每轴 2 次，无法估计 \(R_{t,k}\)。内部基准要：

1. **配对**：同一初始场景、同一随机种子，跑策略 A/B；只切换一个因素（位置/干扰物/背景/未见物/人手动作）。配对差值消掉场景方差。
2. **分层/部分池化**：任务、轴、步骤三层；用 beta-binomial 或分层 logistic 借跨任务信息，避免每格样本太少。
3. **序贯**：SAVI/SPRT/贝叶斯决策，达到“改进后验 > 阈值”或“无望”就停，节省真机/回放。
4. **预注册**：主指标、停止规则、排除规则先写死；避免看到结果后改假设。
5. **校准**：用官方调试槽的少量结果校准 CSP 的预测；若偏差大，先修谓词/场景标签，不急着选模型。

### 2.5 对排名的影响

在成功率优先的字典序下：

- 在条件成功率相近时，提升一个**所有任务都会经过**的步骤（如抓取、放置）比提升某个任务特有的中间步更值钱；
- 提升一个**低到达率**的步骤，要先解决“到达”问题，否则条件成功率再高也没用；
- 提升一个**高到达率、低条件成功率**的步骤，边际收益最大；
- 步骤分的提升只有在成功率同分时才有排名价值，但它是找最弱链的信号。

### 3.2 五条共同瓶颈（第 5 条为赛制/评测外部瓶颈）

1. **语义泛化 ≠ 物理链执行**：知道“叠碗”不等于在碗沿间隙、夹爪行程、遮挡下稳定完成。成功率是乘法链，任何一步接触失败清零。
2. **RGBD 训练 → RGB 推理的传感器错配**：多个强模型族在训练/研究中用 depth/RGBD，但 API 只给 RGB。谁先补回 depth（立体/蒸馏/几何），谁少一个隐藏 domain gap。
3. **反应式策略缺持久场景记忆**：人手把物体移出视野、或把已叠好的碗拿走，策略没有“刚才发生了什么”的状态，容易重复动作或找不到目标。
4. **抓取与放置分开优化**：抓取质量头只看“提起来”，放置策略只看“放下去”；夹持姿态、腕部可达性、物体-容器间隙没有联合约束，导致“抓成功、放失败”。
5. **评测噪声大，容易追噪声**：320 trials、2 次/轴，3–5pp 真实提升可能被淹没；没有配对内部基准，会把随机波动当方法有效。

### 3.3 对我们的启示

- 不要和头部模型拼“更大的 VLA/更多数据”；底座用 WLA-1.0-Base，语义能力够用。
- 要拼**接口级几何**（立体深度/场景图）、**链式诊断**（CSP）、**抓放联合**（G4P）——这三件事是头部模型族的公开路线里相对空白的。
- 世界模型的 test-time chunk 选择（如 DREAM-Chunk [S31]）是可选增强，但不进主线；主线仍是几何 + 链式诊断，避免把 14B 世界模型的自部署成本带进来。
- 单模型合规下，所有学习头必须在同一个 checkpoint；外部感知模型只在离线标注，不进推理。

### 4.2 CSP：链式基准（Chain-Step Profiler）

> 命名说明：这里的 CSP 指 **Chain-Step Profiler**，不是 Constraint Satisfaction Problem。

**目标**：估计每任务每步的 \(R_{t,k}\)，找出最弱链，分配稀缺试验。

**输入**：

- 官方 32 任务 `score_steps` 图；
- 33k 成功演示的相位段（先验，不是失败率）；
- 内部配对回放/局部孪生；
- 官方调试槽/正式跑日志；
- 场景标签（轴、物体、背景、干扰、人手动作）。

**输出**：

- 每任务每步 \(R_{t,k}\) 的后验均值/区间；
- 链式剖面图（任务 × 步骤）；
- 最弱链排序（按“提升边际收益 × 可干预性”）；
- 下一批试验的场景/任务/重复数；
- 模型 A/B 的配对差值后验。

**统计模型（轻量版）**：

对任务 \(t\)、轴 \(a\)、步骤 \(k\)，观测“到达 \(k\) 后是否成功” \(y_{t,a,k}\)。用分层 beta-binomial：

\[
y_{t,a,k}\sim\text{Binomial}(n_{t,a,k},R_{t,a,k}),\qquad
\text{logit}(R_{t,a,k})=\mu+u_t+v_a+w_k+\epsilon_{t,k},
\]

其中 \(u_t,v_a,w_k\) 是零均值随机效应，\(\epsilon\) 是任务×步骤交互。样本少时用部分池化借跨任务信息；样本多时让数据主导。实现可用 NumPyro/PyMC，或先用 beta-binomial + bootstrap 的轻量版。

**配对 A/B**：

- 同一场景种子，策略 A/B 各跑一次；
- 记录首次失败步骤、每步完成、总成功、步骤分；
- 差值用配对 bootstrap 或 McNemar；
- 序贯停止：后验 \(P(\Delta>0)>\eta\) 或 \(P(\Delta<-\delta)<\eta'\)。

**试验分配**：

- 先验最弱链 + 信息增益（Thompson sampling）；
- 每个任务至少 2 个配对种子；重点任务 4–8 个；
- 调试槽优先给“链式剖面分歧最大”的任务，而不是固定 T27/T10。

### 4.3 SGM：任务条件化的度量-语义场景图

**节点类型**：

| 类型 | 关键属性 |
|---|---|
| object | 6D pose、extent、可动/易碎/透明、抓取亲和性、类别/语言别名 |
| container | 6D pose、开口法向、内部尺寸、槽位/挂点、可达性 |
| support | 桌面/架子平面、摩擦/倾斜、支撑多边形 |
| slot/region | 目标位姿/区域、容差、语义标签（leftmost/middle/rack） |
| gripper | 左右 EE pose、开度、负载、可达球 |
| hand/human | 可见人手/工具、运动趋势、干扰置信度 |

**边**：`on`、`in`、`near`、`left_of`、`front_of`、`contains`、`occludes`、`aligned_with`、`supported_by`、`reachable_from`。

**构建**：

1. 4 路 RGB + 双目/单目深度 + proprio；
2. 检测/分割：已知物体用模板/点云；未知物体用轻量分割头（在 checkpoint 内）或经典几何；
3. 6D pose：模板配准/ICP/PnP；容器用平面+开口检测；
4. 关系：几何谓词（距离/包含/支撑/朝向）+ 任务先验；
5. 置信度：多视角一致性、深度重投影误差、时间滤波；
6. 记忆：每 episode 一个图；物体跟踪（Kalman/粒子）；遮挡保留最后位姿+不确定性；人手/机器人动作导致的差分更新；重新出现时重定位。

**用途**：

- 任务 grounding：语言 → 节点/边/槽位；
- 抓取：物体节点上的候选生成/过滤；
- 放置：容器/槽位节点的候选枚举；
- 谓词：`in(cup, hook)`、`stacked(bowl3,bowl2)`、`plugged(plug,strip)`；
- 恢复：人手移动 → 图差分 → 重规划；
- CSP：图关系作为步骤完成的标签。

### 4.4 G4P：抓取-放置联合规划

**候选生成**：

1. **演示模式先验**：从 33k 演示的闭合时刻提取 \(T_{\text{obj}}^{\text{grasp}}\)，按任务/物体聚类；每个模式带频率、宽度、接近方向、左右手。
2. **几何 antipodal 候选**：在物体点云上采样点对，计算平行爪抓取；过滤：
   - 宽度 ≤90mm（Dex1 行程）；
   - 爪长/接近间隙 ≥ 物体高度/容器边缘；
   - 不与支撑/容器/另一臂碰撞；
   - IK 可达（双臂工作空间）；
   - 抓取中心落在可夹截面。
3. **分桶策略**：
   - 小/薄：边缘捏取、侧向抓、top-down pinch；
   - 大/重：power grasp、包络抓；
   - 插入：夹持姿态不挡插入轴；
   - 悬挂：钩/柄朝向可见；
   - 双臂：一手持容器、一手操作；或双手协同。
4. **双臂分配**：对每个候选对 \((g_L,g_R)\) 检查双臂 IK/碰撞/同步；按任务语义（持/插/拧/拉）分配主辅手。

**放置可行性**：

对抓取 \(g\) 和放置候选 \(p\)：

1. 由 \(g\) 计算抓取后物体位姿 \(T_{\text{world}}^{\text{obj}}=T_{\text{world}}^{\text{ee}}\cdot T_{\text{ee}}^{\text{obj}}\)；
2. 检查 \(p\) 的 IK 可达、接近/撤退路径无碰撞；
3. 检查物体-容器间隙、支撑多边形、释放姿态容差；
4. 检查腕部相机可见性（接触/插入需要视觉伺服）；
5. 检查释放后稳定性（叠碗/挂杯/插头）。

**联合评分**：

\[
S(g,p)=\log P_{\text{grasp}}(g)+\log P_{\text{place}}(p\mid g)+\log P_{\text{reach}}(g,p)-\lambda C(g,p).
\]

- \(P_{\text{grasp}}\)：抓取质量头（在 checkpoint 内）；
- \(P_{\text{place}}\)：放置可行性头（在 checkpoint 内）；
- \(P_{\text{reach}}\)：链式先验/CSP 的到达概率；
- \(C\)：路径长度/时间/碰撞风险/重抓代价。

**选择**：

- 取 top-k（k=3–5），用不确定性/几何可行性重排；
- 若 top-1 低于阈值，先重新观察/换视角，不要硬执行；
- 若抓取后发现实际物体位姿与预测差 > 阈值，**运输前重抓**；
- 若放置候选全不可行，回到 SGM 重新选槽位/容器。

### 4.5 与 VLA 的接口

VLA 输入：

- 4 路 RGB + proprio + language；
- SGM token：节点/边特征（物体/容器/槽位/夹爪/人手）+ 6D pose 编码；
- 步骤上下文：SSG 的 \(s_t\)、步骤文本、权重、谓词状态；
- G4P 锚点：选中的抓取位姿/宽度/力、放置位姿/槽位、双臂分配；
- 可选：深度图/点云 token（若深度分支启用）。

VLA 输出：

- action chunk（joint 或 ee）；
- 辅助头：步骤谓词、抓取质量、放置可行性、图节点/边预测、深度（若蒸馏）。

**训练时必须注入推理期会看到的 token**（图 token、锚点、步骤上下文），否则推理期首次见到会崩。

### 4.6 单模型合规设计

- **唯一学习模型**：WLA/GPR-VLA checkpoint，包含所有学习头。
- **确定性代码**：候选采样、antipodal 计算、IK、碰撞、图更新、CSP、SVL 控制循环。
- **离线标注**：可用 SAM/FoundationPose 等生成伪标签，但不进推理容器；提交模型卡披露。
- **外部数据**：默认 OFF；L2L 自采数据需官方确认。
- **模型卡**：列出所有头、训练数据、外部工具、确定性模块；审计时可复现。

## 5. 关键算法

### 5.1 相位切分与步骤标签

输入：33k 演示的 EE 轨迹、夹爪开度、图像、语言。

步骤：

1. 夹爪闭合事件 → 抓取相位；夹爪打开 → 释放相位；
2. EE 速度/加速度 → 接近、运输、退回；
3. 物体-容器关系（SGM 伪标签）→ 放置/插入/堆叠；
4. 与官方 `score_steps` 对齐（每任务 2–5 步）；
5. 人工抽检 5–10%，错误段剔除。

输出：每 episode 的步骤边界、每步时长、抓取/释放时刻、谓词标签。

### 5.2 谓词与链式标签

谓词示例：

| 步骤类型 | 谓词 | 观测 |
|---|---|---|
| 抓取 | gripper_closed_on(obj) | 夹爪开度 + 物体位姿 + 接触 |
| 放置 | in(obj, container) / on(obj, support) | SGM 关系 |
| 堆叠 | stacked(top, bottom) | 相对位姿 + 稳定性 |
| 插入 | inserted(plug, port) | 相对位姿 + 深度/力 |
| 悬挂 | hung(cup, hook) | 相对位姿 + 重力方向 |
| 闭合 | closed(zipper/lid) | 关节/视觉 |
| 整理 | aligned/ordered | 槽位/朝向 |

标签来源：演示伪标签 + 少量人工 + 调试槽校准。谓词头输出概率，低于阈值时用几何/事件兜底。

### 5.3 抓取模式库

对每条演示：

1. 在夹爪闭合时刻，取物体位姿 \(T_W^O\)（SGM/伪标签）和 EE 位姿 \(T_W^E\)；
2. 计算物体系抓取位姿：

\[
T_O^G=(T_W^O)^{-1}T_W^E.
\]

3. 记录夹爪宽度、接近方向、左右手、物体类别；
4. 按任务/物体聚类（SE(3) 位置 + 四元数 + 宽度）；
5. 输出模式：中心位姿、协方差、频率、适用物体尺寸、接近方向。

在线：给定物体节点，取匹配模式 + 几何候选，进入 G4P 评分。

### 5.4 释放位姿库与 OPT

对每条演示：

1. 在夹爪打开时刻，取容器位姿 \(T_W^C\) 和 EE 位姿 \(T_W^E\)；
2. 容器系释放位姿：

\[
H=(T_W^C)^{-1}T_W^E.
\]

3. 统计中位数/四元数均值/离散度 \(\sigma_{xyz},\sigma_\theta\)；
4. 任务容差 \(\tau_{\text{task}}\) 取同任务演示的 95 分位差；
5. 在线：估计当前容器位姿 \(\hat T_W^C\)，检索 K 条行为对齐演示，计算 \(\bar H\)，目标 \(\hat T_W^G=\hat T_W^C\bar H\)。

决策：

```text
σ < τ1          → 直接执行
τ1 ≤ σ < τ2     → 慢速 + 腕部视觉伺服
σ ≥ τ2          → 放弃迁移，退化为锚点伺服 + 保守放置
```

### 5.5 放置可行性评分

对每个放置候选 \(p\)：

```text
feasible(p, g):
  T_obj = T_ee(g) * T_ee_obj(g)
  if not IK_reachable(T_obj, p): return 0
  if collision(T_obj, path(p)): return 0
  if not clearance(T_obj, container(p)): return 0
  if not stable_release(T_obj, support(p)): return 0
  if not visible_to_wrist(p): return 0
  return P_place_head(features(T_obj, p, SGM))
```

特征：相对位姿、容器开口、槽位余量、支撑多边形、物体尺寸/材质、抓取姿态、腕部可达、历史失败。

### 5.6 联合排序伪代码

```python
def grasp_for_place(task, step, sgm, policy, k=5):
    obj = sgm.target_object(task)
    container = sgm.target_container(task)

    grasps = []
    grasps += demo_grasp_modes(task, obj)          # 先验
    grasps += geometric_antipodal(obj, dex1)       # 几何
    grasps = [g for g in grasps if dex1_filter(g, obj)]
    grasps = [g for g in grasps if ik_reachable(g, sgm.robot)]
    grasps = top_k_by_prior(grasps, 32)

    places = sgm.placement_candidates(container, task, step)
    places = [p for p in places if placement_geometry_ok(p, container)]

    scored = []
    for g in grasps:
        for p in places:
            if not joint_feasible(g, p, sgm):
                continue
            s = (policy.grasp_logprob(g, obj)
                 + policy.place_logprob(p, g, obj, container)
                 + csp.reach_logprob(task, step, g, p)
                 - cost(g, p))
            scored.append((s, g, p))

    if not scored:
        return None
    scored.sort(reverse=True)
    return scored[:k]
```

执行：

```python
def execute(task, step, sgm, policy, budget=2):
    for attempt in range(budget + 1):
        cands = grasp_for_place(task, step, sgm, policy)
        if not cands:
            sgm = sgm.reobserve()
            continue
        s, g, p = cands[0]
        if s < THRESH:
            sgm = sgm.reobserve()
            continue

        policy.set_anchor(grasp=g, place=p)
        ok = run_skill(policy, sgm, step)      # VLA chunk + SVL
        if ok:
            return True

        reason = diagnose(step, sgm)
        if reason == "grasp_slip" or reason == "grasp_bad_for_place":
            g = regrasp_candidate(cands)
        elif reason == "place_collision" or reason == "place_misaligned":
            p = next_place_candidate(cands)
        else:
            sgm = sgm.reobserve()
    return False
```

### 5.7 双臂分配

对可能需要双臂/双手协同的任务（如 T05 插网线、T10 插排、T18 背包、T28 耳机盒、T32 注射）：

1. 枚举主手/辅手分配；
2. 检查双臂 IK、碰撞、同步；
3. 按任务语义打分：
   - 持容器的手：稳定、力大、可见；
   - 操作的手：灵巧、腕部自由、接近轴对齐；
   - 插入：辅手持插座，主手插；
   - 拉链/折叠：双手协同，避免互相遮挡。
4. 若双臂不可行，退化为单手 + 支撑/重试。

### 5.8 执行、重试与恢复

- **抓取前**：G4P 选 top-k；低于阈值先重观察。
- **抓取后**：腕部相机估计实际物体位姿；若与预测差 > 阈值，运输前重抓。
- **运输中**：碰撞/滑动监测；异常则停下重规划。
- **放置**：SVL 缓放 + 稳定性/谓词校验；失败则 nudge/regrasp/retry。
- **人手干扰**：SGM 差分检测；若步骤被撤销，SSG 回退；NRB 恢复策略触发。
- **预算**：普通任务 ≤2 次重试；长程任务 ≤1 次；180s 总守卫。

## 6. 数据引擎

### 6.1 33k 演示能提供什么/不能提供什么

| 能提供 | 不能提供 |
|---|---|
| 抓取模式（闭合时刻相对位姿） | 每步失败率（演示全成功） |
| 释放位姿（打开时刻容器系） | 人为干扰响应（演示无干扰） |
| 相位时长/顺序 | 未见物体/背景的失败分布 |
| 语言复述（5 条/任务） | 真实评测的轴级场景 |
| 物体/容器/槽位伪标签 | 接触力/滑移标签（无触觉） |
| 双臂协同模式 | 真实机器人的延迟/故障 |

### 6.2 建库流程

1. **抽样**：每任务 100–300 条（不是全部 1k），覆盖不同物体/位置/背景。
2. **标定**：相机重投影 <5px、桌面 <5mm、EE 回放 <2cm；双目基线/外参。
3. **相位切分**：夹爪事件 + EE 运动 + SGM 关系。
4. **抓取/释放库**：按 §5.3/§5.4 统计；抽检 10%，误差 <1cm 才入库。
5. **场景图伪标签**：多视角三角化 + 模板/点云；透明/反光物体标记低置信。
6. **版本化**：`grasp_modes/<task>.npz`、`release_poses/<task>/<step>.npz`、`sg/<episode>.npz`。

### 6.3 扰动与配对场景

| 轴 | 生成方式 | 用途 |
|---|---|---|
| 位置 | 物体/容器平移/旋转（桌面内） | 抓取/放置泛化 |
| 干扰物 | 路径旁插入刚体杂物 | 碰撞/遮挡 |
| 背景 | 桌布颜色/纹理替换 | 视觉鲁棒 |
| 未见物 | 同类不同外观资产替换 | 语义/几何泛化 |
| 人为干扰 | 官方备注剧本（1-DOF 平移/撤销） | 恢复/记忆 |

配对：同一场景种子，只改一个因素；A/B 策略各跑一次。局部回放/孪生用 Unitree 仿真/训练栈 [S36]，只做相对比较，不做绝对成功率承诺。

### 6.4 数据配比

| 数据 | 用途 | 比例（建议） |
|---|---|---:|
| 真实 33k | 主训练 | 60–70% |
| 真实 hard cases（调试槽/失败回放） | 链式弱点 | 10–15% |
| 局部回放/合成扰动 | 轴覆盖/负样本 | 15–20% |
| NRB 恢复对 | 人手干扰 | 5–10% |
| L2L 外部 | 背景/位置（默认 OFF） | 0%（确认后 ≤20%） |

原则：合成不主导；真实成功演示保底；失败/扰动样本加权但不淹没成功分布。旁证：导航数据缩放显示多样性比数量更重要 [S33]；本方案把背景/位置多样性放在 L2L 与扰动场景，而不是盲目增加演示条数。

## 8. 评测协议

### 8.1 三级评测

| 级别 | 频率 | 内容 | 用途 |
|---|---|---|---|
| 离线 | 每天 | 谓词 F1、位姿误差、抓取模式覆盖、G4P top-k 可行性 | 快速迭代 |
| 局部配对 | 每周 | 8 任务 × 5 轴 × 4 种子 × A/B | 模型选择/消融 |
| 官方调试槽 | 版本门 | 2–3 任务，5–10 trials | 校准/发布门 |
| 官方计分跑 | W7/W8 | 32 任务 × 10 | 最终排名 |

### 8.2 CSP 统计模型

- 轻量版：beta-binomial 部分池化 + 配对 bootstrap；
- 完整版：分层 logistic + NumPyro；
- 停止规则：后验 \(P(\Delta>0)>0.95\) 或最大样本；
- 多重比较：按任务/轴分层，Benjamini–Hochberg 或分层收缩；
- 校准：用调试槽结果做 posterior predictive check；偏差大则修谓词/场景标签。

### 8.3 任务选择

优先选择链结构不同的任务，而不是只看难度：

| 任务 | 链结构 | 为什么选 |
|---|---|---|
| T27 StackBowls | 抓→放→叠→叠 | 放置/堆叠/稳定性 |
| T10 PlugCharger | 抓排→抓头→插 | 插入/双臂/力控 |
| T01 HangCup | 抓→挂 | 悬挂/钩对准 |
| T13 ArrangeTestTubes | 抓→放回架 | 小物体/槽位 |
| T26 PlugInEthernet | 抓线→持口→插 | 柔性物/双臂 |
| T16 FoldTowel | 多步折叠 | 长程/布料（谨慎） |
| T17 OrganizeStationery | 多步放置→闭合 | 长程/闭合 |
| T28 StoreEarphones | 抓→放→放→闭合 | 小件/双臂/闭合 |

调试槽有限时：先 T27/T10/T01（三种链），再 T13/T26（小件/柔性）。

### 8.4 消融

| 消融 | 验证 |
|---|---|
| SGM on/off | 遮挡/干扰/位姿误差 |
| G4P joint vs grasp-only vs place-only | top-1 可行性/成功率 |
| demo 模式 vs 纯几何 | 候选覆盖/泛化 |
| 双目 vs 单目 vs 无深度 | 放置误差/插入成功率 |
| 双臂分配 on/off | 双臂任务成功率 |
| CSP 配对 vs 官方 10 次 | 检测 3–5pp 的 power |
| 链式重试 vs 固定重试 | 总时长/成功率 |
| NRB 官方剧本 vs 随机扰动 | 恢复成功率 |

### 8.5 验收标准

- 离线：谓词 F1 ≥0.85；物体/容器位姿 <1cm/5°；G4P top-1 几何可行 ≥90%；top-5 覆盖 ≥95%。
- 局部配对：G4P 相对 grasp-only 的放置可行性 +10pp（配对后验 >0.95）。
- 调试槽：终局步条件成功率 +10pp 且无回归；或总成功率 +5pp。
- 正式跑：总平均成功率 +3pp 目标；步骤分不下降；无超时/部署故障。

## 9. 创新点清单（持续迭代；动机/差异/可行性/资源/步骤/风险/状态）

> 状态：押注=本轮主线；保留=沿用；升级=旧点改造；降级=保留但非主回路；砍=不做。

### I1 SSG 评分步骤图门控（保留，修正定位）
- 动机：官方步骤/权重公开；成功=全步骤；防跳步/假完成。
- 差异：从“步骤分优化器”改为“链式状态与谓词骨架”，服务 CSP/G4P。
- 可行性：确定性图 + 谓词头；32×5 复述可匹配。
- 资源：无额外数据；1 人周。
- 风险：谓词噪声 → 演示统计校准；语言未覆盖 → 嵌入兜底。

### I2 PGL 放置目标阶梯（保留，接入 G4P）
- 动机：显式槽位/锚点/位姿比 VLM 直接坐标稳；AnySlot/SpaceVLA 证据。
- 差异：槽位/锚点作为 G4P 的放置候选，不再单独决定。
- 可行性：投影/渲染确定性；接口允许图像缩放。
- 风险：锚点域差 → 训练/推理同渲染；透明物体 → 回退几何。

### I3 OPT 释放位姿迁移（保留，作为 G4P 先验）
- 动机：33k 演示有释放位姿；K 条统计可跨场景。
- 差异：迁移容器系相对位姿统计 + 离散度，不复制轨迹。
- 可行性：EE base 位姿 + 容器检测；零梯度。
- 风险：容器位姿估计失败 → 分桶回退。

### I4 ICR 上下文检索（降级为辅路）
- 动机：检索式 VLA 证据强；33k 是现成库。
- 差异：从主押注降为“抓取模式/相位上下文检索”，服务 G4P。
- 可行性：缓存编码控延迟；HNSW。
- 风险：延迟/透明任务失效 → 关掉，不影响主线。

### I5 SVL 落点闭环（保留）
- 动机：终局释放失败靠“放完就完”发现不了。
- 差异：缓放→稳定/谓词校验→nudge/regrasp。
- 可行性：腕部相机 + 谓词；180s 够 1–2 次。
- 风险：耗时/误判 → 双阈值 + 预算守卫。

### I6 NRB 官方备注恢复（保留）
- 动机：human 备注公开，多为平移/撤销剧本。
- 差异：官方剧本回放 + 通用扰动兜底。
- 可行性：1-DOF 刚体变换，合成/回放便宜。
- 风险：备注编号含义未核实 → 同时覆盖通用扰动。

### I7 L2L 产学研数据（降级，默认 OFF）
- 动机：背景/位置轴本质是场景多样性。
- 差异：逐字段对齐的采集协议 + QA + 许可。
- 可行性：高校 G1 网络已公开；但外部数据规则未读。
- 风险：规则不允许 → 转赛后；硬件异构 → 限定 G1+Dex1。

### I8 DebugLoop 平台调试回路（升级为 CSP 校准）
- 动机：真机反馈比自建孪生可信。
- 差异：调试槽不再固定 T27/T10，而由 CSP 的信息增益选任务。
- 可行性：官方提供不计分单任务调试；次数未知。
- 风险：稀缺/规则变化 → 每版本最多 1–2 槽。

### I9 GPR-VLA + WLA 主干（保留）
- 动机：谓词残差 + 可逆信念与链式结构对齐；Apache-2.0。
- 差异：新增图 token/抓放锚点/辅助头，仍是唯一 checkpoint。
- 风险：底座微调不足 → LoRA 分级；头太多 → 辅助损失降权。

### I10 TLE/ACP/GF 数据引擎（保留，聚焦链式）
- 动机：真实锚定的反事实最便宜。
- 差异：从“全任务密集标签”收窄到“相位/抓放/谓词/扰动”。
- 风险：合成负迁移 → GF 软权重 + 真实混采。

### I11 AH-TP / Endurance / Compliance（保留）
- 作用：谓词时长监督、180s 守卫、数据来源开关、单模型审计。

### I12 TCLB → CSP（升级，押注）
- 动机：官方 320 trials 无法做模型选择/轴级归因。
- 差异：条件成功率 + 配对 + 部分池化 + 序贯 + 试验分配。
- 可行性：轻量统计可先跑；真机数据从调试槽来。
- 资源：1 人 × 2 周；Python/NumPyro。
- 步骤：场景库 → 配对回放 → 分层模型 → 校准 → 选型。
- 风险：场景标签错 → 先修谓词；样本少 → 部分池化。

### I13 FLEET 工程检查单（保留，降级）
- 保留：N 端口、状态隔离、RTC 式延迟弹性、健康检查。
- 不再当“第六轴”研究贡献。

### I14 G4P 抓取-放置联合排序（新增，押注）
- 动机：抓得稳 ≠ 抓得能放；Dex1 几何 + 抓放联合规划证据。
- 差异：抓取候选按下游放置可行性排序；运输前可重抓；双臂分配。
- 可行性：33k 演示模式 + 几何候选 + IK/碰撞；学习头在 checkpoint。
- 资源：8×H100 建库/训练 2–3 周；规划器 CPU/GPU。
- 步骤：模式库 → 候选生成 → 可行性头 → 联合排序 → 调试槽。
- 风险：候选组合爆炸/评分不准 → top-k + 几何硬过滤 + 真机校准。

### I15 SGM 度量-语义场景图（新增，押注）
- 动机：API 无 depth；遮挡/人手干扰需要持久状态；抓放需要共享几何。
- 差异：任务条件化桌面图，不是通用 SLAM；图 token 进 VLA。
- 可行性：双目/单目深度 + 模板/点云 + 轻量头；图更新确定性。
- 资源：标定 1 周；伪标签 1–2 周；训练 1 周。
- 步骤：标定 → 图 schema → 伪标签 → 图编码 → 记忆/差分 → 调试槽。
- 风险：透明/小件位姿错 → 不确定性 + 回退；双目不成立 → 单目蒸馏。

### I16 双目/单目深度接口（新增，高优先）
- 动机：训练数据有双目，API 无 depth；传感器错配是隐藏 gap。
- 差异：优先用高位双目恢复度量深度；否则蒸馏单目深度头进 checkpoint。
- 可行性：数据集双目已校正；API 需验证；SGBM 经典/蒸馏。
- 资源：标定 3–5 天；蒸馏 1 周。
- 风险：API 两路不是双目/未标定 → 回退平面/模板；深度噪声 → 多视角融合。

### I17 链式重试预算（新增，中优先）
- 动机：不同步骤的失败代价不同；固定重试浪费 180s。
- 差异：按 CSP 的 \(R_{t,k}\) 和剩余时间分配重试；高价值步骤多给。
- 可行性：CSP 输出 + 计时器；确定性。
- 风险：CSP 不准 → 保守上限；长程任务 → 总守卫。

### I18 双臂抓取分配（新增，中优先）
- 动机：多个任务需要持容器/插/拧/拉；单手策略浪费自由度。
- 差异：G4P 内枚举主辅手，检查双臂 IK/碰撞/语义。
- 可行性：API 有双臂；数据集有双臂演示。
- 风险：双臂碰撞/同步 → 先单臂+支撑，逐步放开。

### 已砍清单（跨轮）
- “步骤分优先”的排名假设；终局唯一瓶颈的单一归因；推理期外部感知模型；每任务 LoRA；全 32 任务高保真孪生；自由仿真数据；运行时 MPC；世界模型作为主策略；大规模合成数据主导训练。
