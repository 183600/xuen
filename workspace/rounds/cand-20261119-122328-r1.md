# 第 1 轮（本轮灵感：「桌面操作」×「路径规划」；技术基线延续 v15）

> **基线**：第 13 轮 MetricVoiceGauge-NCD-HUTDH v15（技能扩散版：SCD/DSD/DCA/EDC，定义 607–626；引理 125–130；实验 E661–E670）。
> 本轮纪律：**支撑优先的接触走廊证书 + 同伦骨架的相对完备性 + 走廊—技能的单调投影**。不推倒 v15：v15 的 SCD/DSD/DCA/EDC、v13 的 AIO/CPD/DGC/DDL/RTCR、v12 的 USG/TGC/BAA/GAGP/UC、v11 的 HAS/HCC/HATD/HDT、v10 的 NGE/DSL/CC/CWM/CAE/NCP、v9 的 AC/MW/ID、v8 的 DA/SPR/Cal 与九不变式全部保留。四个新组件——TCP（桌面接触走廊规划器）、SSE（支撑稳定性包络）、HSC（同伦骨架覆盖）、CDG（走廊漂移守卫）——一律以**中立元**接入，失效即严格退回 v15（引理 140），再沿 v15→v14→…→v6 退化链退回。本轮只做三件事：把"路径"从几何无碰撞改写为**支撑可证的接触走廊**、把"桌面操作"从离散技能选择改写为**沿走廊的接触事件序列**、把二者合成一个**共享同一套支撑不变式的执行对象**。

## 0. 直觉与动机

**灵感 1（桌面操作 → 重力的世界：支撑不变式是一等公民）**
直觉：桌面与一般自由空间的最大差别不是"有桌子"，而是**重力把每个物体钉在一个支撑关系里**。机器人真正会犯的灾难性错误——把杯子推下桌、让一摞盘子倾倒、夹起物体却带翻旁边的东西——都不是"路径碰到了障碍"，而是**支撑关系被破坏**。现有流水线先规划一条无碰撞臂路径、再选一个抓取，二者各自看都对，合起来却可能在某一帧让某物体的质心投影移出支撑多边形。核心创新：**把支撑不变式 `I_sup` 提升为路径的硬约束**，规划在增广状态 `X = C_arm × Ω_obj × Σ_sup`（臂构型 × 物体位姿 × 支撑图）中进行；一条可执行路径必须是一条**接触走廊**——沿廊每一截面都同时满足碰撞余量、支撑稳定、可达性与摩擦锥证书。反直觉点：**不该把"避障"当作主目标、把"稳定性"当作事后检查**；在桌面上，先固定支撑不变式、再在不破坏它的子空间里找路，往往比先找短路径再修补更完备，因为支撑约束天然把状态空间切成有限个可枚举的支撑图连通块。

**灵感 2（路径规划 → 同伦骨架：有限类覆盖换取可声明的完备性）**
直觉：采样规划器的"找不到"永远分不清是"真无解"还是"没采到"。经典路径规划之所以能有完备性，是因为它利用了拓扑结构——单元分解把连续空间切成有限块，同伦类把无穷多条路径压成有限个本质不同的走法。桌面恰好提供了这种结构：在有限的支撑图与障碍排布下，绕过/越过/穿过某个缝隙的路径分属有限个同伦类；每个类对应一组本质不同的接触机会（从左边接近还是从右边、先移开 A 还是先移开 B）。核心创新：**同伦接触骨架（HSC）先枚举有限个骨架类 `{K_1…K_M}`，再在每个类内用连续走廊细化**。于是系统能诚实地输出三种结论之一：某类内存在已证走廊；所有已覆盖类内都不存在（**相对不可行证书**，附带未覆盖类与离散化假设）；覆盖本身不足（显式声明未覆盖测度 `η` 并回退）。这把"完备性"从不可证的广告词变成**带前提、可审计的证书**。

**灵感 3（桌面×路径 → 走廊与技能互为投影、退化只收缩扰动集）**
直觉：v15 已经把动作组织成带证书的技能阶梯；本轮发现"接触走廊"和"技能序列"其实是同一对象的两视图——走廊是技能在增广空间里的**几何实现**，技能是走廊在离散决策层的**符号抽象**。二者双向投影后，路径规划器不再另起炉灶，而是复用 v15 的证书、随时机制与蒸馏阶梯。更强的是，桌面给了退化一个**天然的单调量**：越保守的档位，允许扰动的物体集合越小。于是退化阶梯可以写成 `disturb(第 0 档) ⊆ disturb(第 1 档) ⊆ … ⊆ disturb(第 m 档)`：时间紧、漂移大、遮挡重时，只收缩"我允许自己碰哪些物体、移动多远"，而不改变安全判据。统一为 `Exec_v16 ⊆ Exec_v15` 的实现层：v15 回答"哪些技能被授权"，v16 回答"用哪条可证走廊把这些技能落到桌面上"。

**三者如何统一**
统一为 **v15 决策层之下的桌面实现层**：共享状态 `ζ_tab = (X̂, Σ̂, Skel, k*, Γ, m_sup, U_pos, mode)`。SSE 提供支撑不变式与余量；HSC 提供有限骨架与覆盖证书；TCP 在选定骨架内生成并保守扩张接触走廊 Γ；CDG 在线守卫"实际状态是否仍在 Γ 内"。**SSE 回答"什么状态在重力下是稳的"，HSC 回答"有没有本质不同的走法还没试"，TCP 回答"这条走法能否被逐段证明"，CDG 回答"实际执行有没有走出证明"**。四者不是四个新功能，而是"支撑—拓扑—走廊—守卫"的一条证书链。

## 1. 研究问题（轮次升级版）

- **Q1（接触走廊的可证语义）**：如何在增广空间 `X` 上定义走廊，使"跟踪误差界内、任意时刻"都保持 `I_sup`？运输段与接触段如何在接缝处拼接而不丢证书？抬升/放置这类**瞬态改变支撑图**的动作如何被证，而不是被当作例外跳过？
- **Q2（相对完备性的可声明边界）**：如何枚举有限的同伦骨架类，使未覆盖测度 `η` 可计算或可上界？物体位姿连续、支撑图组合爆炸时，哪些类可被安全剪枝而不破坏完备性声明？覆盖证书在支撑图变化后是否还成立？
- **Q3（支撑证书的成本与精度）**：摩擦锥、质心投影、多点支撑的稳定性判定能否在 22ms 内以可证精度完成？姿态不确定性 `U_pos`、物体模型覆盖率 `ρ_obj` 如何传导为支撑余量的折减？怎样复用 v15 的 anytime 与蒸馏而不重复支付证书成本？
- **Q4（兼容、活性与死锁）**：走廊塌缩到最保守档是否会清空可行集，造成"越保守越卡死"？出现未见物体或桌面被人为移动时，HSC 是否会把"骨架失效"错误地报成"相对不可行"？新增模块能否守住 50Hz/p99≤22ms，并严格退回 v15？

## 2. 设计原则（在 P22–P24 基础上新增 P25–P27）

**P25 支撑优先律（Support First）**
任何被执行的动作必须保持支撑不变式 `I_sup`。若某任务在几何上必须瞬态破坏桌面支撑（如抬起物体），必须显式携带"持有—支撑转移"证书，并在转移窗口内把支撑责任从桌面移交给夹爪或另一物体。任何时刻支撑余量不得低于已证下限 `m_sup^min`；**不得**用"平均稳定"或"事后回正"替代逐帧支撑证书。

**P26 走廊不变律（Corridor Invariance）**
实际执行必须停留在已证走廊 Γ 内（含跟踪误差、滑移、遮挡导致的位姿漂移）。一旦越界，只能沿预注册的退化阶梯收缩到更短的前缀走廊或安全停靠；**禁止在线外推或临时补证一条新走廊来"救场"**。走廊每个截面的证书必须以同一判据复算，不得缓存跨分布已失效的旧证书。

**P27 同伦诚实律（Homotopy Honesty）**
完备性只能在已覆盖的骨架类内声明。输出"无解"时必须降级为"相对不可行证书"，明确列出 `η`（未覆盖测度）、离散化分辨率 `δ`、以及所依赖的支撑图假设；不得把采样失败包装成"物理不可行"。

## 3. 与基线的接口（如何退化）

- TCP 失效 ⇒ 退回 v15 的"离散技能 + 固定预抓取位姿"路径，不再有走廊，`Exec ≡ Exec_v15`；
- SSE 失效 ⇒ 支撑判定退化为"仅桌面单点支撑 + 顶抓"，只允许孤立物体的保守操作，等价 v15 技能子集；
- HSC 失效 ⇒ 骨架退化为单类（平凡同伦），可能漏解但保持 sound；
- CDG 失效 ⇒ 走廊在首个检查周期后收缩为当前状态，即 v15 的安全停靠；
- 四者全失效 ⇒ v15，再沿 v15→v14→v13→…→v6 退化链；
- **安全继承**：SSE 只收紧支撑约束，HSC 只增加可审计的类，TCP 只在类内扩张已证段，CDG 只做收缩。四端口均不能新增授权或放宽 v15 阈值；`Exec_v16 ⊆ Exec_v15` 由引理 133 与引理 140 保证。

## 4. 预期贡献

1. **接触走廊证书**：把桌面操作与路径规划统一为增广空间里"逐截面可证的支撑走廊"，并把重力/支撑从软惩罚提升为硬约束；
2. **同伦接触骨架覆盖**：给出带未覆盖测度与离散化假设的**相对完备性证书**，把"找不到"从失败变成可审计的否定命题；
3. **走廊—技能双向投影**：证明桌面实现层与 v15 决策层共用证书与退化阶梯，得到 `Exec_v16 ⊆ Exec_v15`；
4. **扰动集单调退化**：让"允许扰动的物体集合单调收缩"成为退化的统一度量，避免越保守越死锁；E671–E690 覆盖走廊 WCET、支撑零违规、覆盖完备性、遮挡/滑移、消融与端到端。

## 5. 本轮最大风险

**一句话**：走廊证书全部建立在**对物体位姿与支撑图的信念**之上；在遮挡、透明/反光物体与滑移下，信念可能已经错了，而证书仍会自洽地在"一个被幻觉出来的支撑图"上逐段成立，最终执行出一条处处可证、却把杯子推下桌的安全决定——即**证书正确、物理错误**。

# IP-403 Support-Stability Envelope：支撑稳定性包络
class SupportStabilityEnvelope:
    def __init__(self, object_models, calib, mu, u_pos, m_min):
        self.models = object_models       # 物体几何/质量/摩擦模型
        self.calib = calib                # 位姿与摩擦的共形校准集
        self.mu = mu                      # 区间摩擦系数
        self.u_pos = u_pos                # 位姿不确定性上界 U_pos
        self.m_min = m_min                # 支撑余量下限 m_sup^min
        self.eps_cal = calib.finite_sample_error()

    def support_margin(self, obj, support_set):
        com_xy = obj.pose.apply(obj.com_local)[:2]
        poly = convex_hull([s.contact_polygon_world() for s in support_set])
        d_com = signed_distance(com_xy, poly)          # 质心投影到支撑边界
        d_fric = self.friction_margin(obj, support_set)  # 摩擦锥余量
        return min(d_com, d_fric)

    def certified_margin(self, obj, support_set):
        # 保守折减：位姿不确定性按 Lipschitz 传播，再减去有限样本误差
        raw = self.support_margin(obj, support_set)
        return raw - self.L_s * self.u_pos - self.eps_cal

    def invariant_holds(self, X):
        for o in X.objects:
            if self.certified_margin(o, X.sigma.support_of(o)) < self.m_min:
                return False
        return all(not o.off_table for o in X.objects)

    def support_transfer_certificate(self, held_obj, gripper):
        # 抬升/放置：支撑责任从桌面移交给夹爪（或反向），必须全程有支撑
        return self.invariant_holds_with_handoff(held_obj, gripper)


# IP-404 Homotopy Skeleton Coverage：同伦骨架覆盖
class HomotopySkeletonCoverage:
    def __init__(self, tabletop, delta, eta_max):
        self.tabletop = tabletop
        self.delta = delta               # 离散化分辨率
        self.eta_max = eta_max           # 可接受未覆盖测度

    def enumerate_skeletons(self):
        # 由障碍排布 + 支撑图切分出的有限同伦类代表
        cells = self.tabletop.cell_decomposition(self.delta)
        classes = group_by_homotopy(cells)
        return [self._representative(c) for c in classes]

    def coverage_certificate(self, skeletons):
        covered = measure_of_union([k.footprint for k in skeletons])
        total = measure_of(self.tabletop.task_relevant_free_space)
        eta = max(0.0, 1.0 - covered / total)
        return Coverage(eta=eta, delta=self.delta,
                        assumptions=self.tabletop.support_assumptions(),
                        complete=(eta <= self.eta_max))

    def select_and_prove(self, skeletons, budget, tcp, x0):
        # 先按下界代价排序；每个类内交给 TCP 逐段证
        for K in sorted(skeletons, key=lambda k: k.lower_bound_cost):
            corridor = tcp.plan_prefix(x0, K, budget)
            if corridor.is_full():
                return corridor, "FOUND"
            if budget.exhausted():
                break
        cov = self.coverage_certificate(skeletons)
        return None, ("RELATIVE_INFEASIBLE" if cov.complete else "COVERAGE_GAP")


# IP-402 Tabletop Contact-Corridor Planner：接触走廊规划
class TabletopContactCorridorPlanner:
    SEG = ("TRANSPORT", "PUSH", "GRASP", "LIFT", "PLACE", "RETRACT")

    def __init__(self, arm, sse, planner):
        self.arm = arm
        self.sse = sse                   # 支撑证书由 SSE 统一给出
        self.planner = planner           # 类内连续路径规划器（完整性锚）

    def safe_stop_corridor(self, x0):
        # 保守起点：只包含"停在当前构型并保持支撑"的零长度走廊
        return Corridor(path=[x0], r=0.0,
                        certs=[self._certify_state(x0)], prefix=0)

    def plan_prefix(self, x0, skeleton, budget):
        corridor = self.safe_stop_corridor(x0)
        for seg in skeleton.events:
            if budget.exhausted():
                break
            cand = self.extend(corridor, seg)      # 连续细化 + 半径扩张
            if not self.certify_segment(cand, seg):
                break                              # 失败只保留已证前缀
            corridor = cand
        return corridor

    def extend(self, corridor, seg):
        x_tail = corridor.path[-1]
        if seg.kind == "TRANSPORT":
            seg_path = self.planner.plan_free(x_tail, seg.goal,
                                              clearance=corridor.r)
        else:
            seg_path = self.planner.plan_contact(
                x_tail, seg.action, seg.contact_model,
                support=self.sse)
        return corridor.append(seg_path, seg)

    def certify_segment(self, cand, seg):
        for x in cand.sampled_at(self.delta):
            # (1) 碰撞余量  (2) 支撑不变式  (3) 可达/去xterity  (4) 摩擦锥
            if not (self.arm.collision_margin(x) >= cand.r
                    and self.sse.invariant_holds(x)
                    and self.arm.reachable(x)
                    and self.friction_cone_ok(x, seg)):
                return False
        return True

    def _certify_state(self, x):
        return self.sse.invariant_holds(x) and self.arm.collision_margin(x) >= 0

    def friction_cone_ok(self, x, seg):
        if seg.kind == "TRANSPORT":
            return True
        return inside_friction_cone(seg.contact_wrench(x),
                                    self.sse.mu[x.support_obj])


# IP-405 Corridor Drift Guard：走廊漂移守卫
class CorridorDriftGuard:
    RUNG = {0: "STOP", 1: "PREFIX", 2: "FULL"}   # disturb 单调收缩方向

    def __init__(self, tau_tr, sse):
        self.tau_tr = tau_tr
        self.sse = sse
        self.mode = 2

    def step(self, x_actual, corridor, slip_signal, intrusion):
        if slip_signal or intrusion:
            return self._degrade(1)
        d = dist_X(x_actual, corridor.path)        # X 度量下到走廊的距离
        if d > min(self.tau_tr, corridor.r):
            return self._degrade(1)
        if not self.sse.invariant_holds(x_actual):
            return self._degrade(0)                # 支撑已被突破：直接停
        return corridor

    def _degrade(self, level):
        self.mode = min(self.mode, level)
        # 只收缩允许扰动的物体集合与位移，不改安全判据
        return self.mode

    elif corridor is not None:

## 3. 推导

**引理 131（走廊不变性 ⇒ 逐时支撑安全）** 设名义路径 `π` 上每个采样截面 `x` 满足 `c_s(x) ≥ (κ, m_min, 0, 0)`，且对实际状态 `x_t` 有 `d_X(x_t, π) ≤ r ≤ τ_tr`。若各证书余量关于 `X` 度量 `L_c`-Lipschitz，则任意时刻支撑不变式成立，且可证余量
```
m_sup(x_t) ≥ m_min − L_c·τ_tr 。
```
证明：由 `x_t` 落在 `π` 的 `r`-管状邻域内，最近点 `x* ∈ π` 满足 `d_X(x_t, x*) ≤ τ_tr`；由 Lipschitz 性，`m_sup(x_t) ≥ m_sup(x*) − L_c τ_tr ≥ m_min − L_c τ_tr`。逐段归纳并用引理 136 处理接缝，即得全时成立。∎ 推论：**安全性只取决于"实际是否留在走廊内"，规划精度只影响进度**；这与 v13 的 anytime 哲学一致——早退只会更保守。

**引理 132（位姿不确定性的支撑余量传导）** 设 `U_pos` 为共形位姿误差上界，`P(‖pose−pose_hat‖ ≤ U_pos) ≥ 1−α_pos`，`m_sup` 关于位姿 `L_s`-Lipschitz。则折减余量 `m_sup^cert = m_sup(pose_hat) − L_s U_pos − ε_cal` 满足
```
P( m_sup^cert ≤ m_sup(pose_true) ) ≥ 1 − α_pos − α_cal 。
```
证明：以概率 `1−α_pos` 有 `‖pose_true−pose_hat‖ ≤ U_pos`，由 Lipschitz 得 `m_sup(pose_hat) − L_s U_pos ≤ m_sup(pose_true)`；再减去校准集有限样本误差 `ε_cal`（覆盖概率 `1−α_cal`），联合界给出结论。∎ 推论：**不确定性只会线性吃掉支撑余量**；遮挡越重，`U_pos` 越大，必须相应抬高 `m_sup^min` 或收缩 `disturb`。

**引理 133（走廊—技能投影的授权包含）** 设技能目录完整（任一走廊段可投影为 v15 的某技能 `s`，且 `cert_s ⊆ Acc_s`）。则对任意已证走廊 `Γ`，其可执行动作集
```
Exec(Γ) ⊆ Exec_v15 ，从而 Exec_v16 ⊆ Exec_v15 。
```
证明：TCP 的每段证书由"碰撞 + 支撑 + 可达 + 摩擦锥"合取而成，且按构造逐项蕴含该段所投影技能的 v15 授权条件；SSE 只收紧支撑约束，HSC 只选择骨架，CDG 只做状态筛选，均不新增动作。故 `Exec(Γ) ⊆ ⋃_s Acc_s = Exec_v15`。∎ 推论：**桌面实现层是 v15 的下层实现，而不是新的授权来源**；技能目录不完整时该包含关系失效，必须显式声明（见引理 139）。

**引理 134（同伦骨架的相对完备性）** 在已覆盖骨架类 `K_i` 内，若存在一条在分辨率 `δ` 下可行的走廊，且类内规划器在该离散化下完备，则 HSC 枚举到 `K_i` 后 TCP 必找到一条可行走廊（允许 `O(δ)` 的余量损失）。若所有已覆盖类均未找到，则不存在已覆盖类内的可行走廊。证明：`K_i` 的单元分解保持同伦类内连通性；类内完备规划器在 `δ`-网上的完备性保证找到代表路径；走廊证书在 `δ` 采样下由引理 131 成立。∎ 推论：**"无解"只能是"相对不可行"**——必须同时报告 `η`、`δ` 与支撑图假设；这是 P27 的数学形式。

**引理 135（退化阶梯的扰动集单调性）** 退化阶梯 `M_0 ≺ M_1 ≺ … ≺ M_m` 满足
```
disturb(M_0) ⊆ disturb(M_1) ⊆ … ⊆ disturb(M_m) ，
```
且每次 `CDG` 退化只会把 `mode` 移到更小的档位。证明：构造每档时按"允许接触的物体子集 × 最大位移 × 允许接触模式"逐项取子集；`_degrade` 只做 `min` 更新。∎ 推论：**退化在安全方向上单调，但在活性方向上可能单调变差**；必须为第 0 档预留非空停靠集（否则死锁，见引理 138）。

**引理 136（走廊拼接的证书保持）** 设 `Γ_1` 终点为 `x`，`Γ_2` 起点为 `x'`，`d_X(x, x') ≤ τ_tr`，二者各自满足引理 131。则拼接走廊 `Γ_1⊕Γ_2` 在不额外补段时满足支撑不变式，余量下降不超过 `L_c τ_tr`；若 `d_X(x,x') > τ_tr`，必须显式证明一段桥接走廊，否则拼接不成立。证明：对接口处取最近点并用三角不等式与 Lipschitz 性；超过界时两段证书无法覆盖中间状态，故需桥接。∎ 推论：**接触事件的顺序不是免费拼接的**，每个"抓—移—放"交界都要支付一次接口证书。

**引理 137（覆盖—余量—算力三难下界）** 在 `d` 维任务自由空间中，任何以 `r`-管覆盖、以分辨率 `δ` 离散化的走廊证书器若只允许 `B_corr` 段证书，则其未覆盖测度满足
```
η ≥ 1 − O( B_corr · (r/δ)^d )  ，
```
或等价地 `B_corr = Ω( (1−η)·(δ/r)^d )`。证明：以 `r`-球覆盖自由空间，体积下界要求至少 `Ω((1−η)(R/r)^d)` 个球；每个证书段至多覆盖常数个球，取 `R=Θ(δ·B_corr^{1/d})` 即得。∎ 推论：**"完备 + 高余量 + 低算力"不可能同时成立**；`B_corr`、`η`、`r`、`δ` 四者必须显式交换。

**引理 138（滑移/漂移下的安全塌缩与活性损失界）** 当滑移、遮挡超界或人体入侵触发 CDG 时，走廊塌缩到安全停靠档；碰撞/掉落等物理硬违规概率不高于 v15 的对应停靠。活动性损失满足
```
P(无可执行已证动作) ≤ P(位姿误差 > U_pos) + P(漂移/滑移) + P(入侵) + P(预算耗尽) + P(物体在模型覆盖外) 。
```
证明：各触发事件之并覆盖所有导致"无已证走廊"的情形；停靠档由物理构造保证安全，且第 0 档预留非空停靠集。∎ 推论：**漂移时不是用更长的走廊去赌，而是用最短的停靠买重感知时间**。

**引理 139（覆盖证书不跨支撑图传递）** 若支撑图由 `Σ` 变为 `Σ'`（新物体出现、物体被移动、遮挡改变可达面），则基于 `Σ` 的覆盖证书 `Cov` 对 `Σ'` 无效；在新图上声明完备性前必须重建骨架并重新计算 `η`。证明：同伦类与支撑图绑定，`Σ` 到 `Σ'` 的映射未必保持同伦类；未覆盖测度依赖任务自由空间，而后者随支撑关系改变。∎ 推论：**"没找到"在桌面被改变后不能复用**；这也解释了为什么 HSC 失效时必须退回单类而非沿用旧覆盖。

**引理 140（全失效严格退回 v15）** 令 TCP 输出空走廊、SSE 取平凡支撑恒真、HSC 退化为单类、CDG 恒返回 FULL，则 v16 主路径与 v15 逐模块等价，即
```
Exec_v16|_{失效} = Exec_v15 。
```
证明：空走廊使 TCP 不新增任何动作；SSE 恒真不收紧也不放宽；HSC 单类只保留 v15 已有路径；CDG 不改变状态。四项均经中立元接入，主闭环末尾的 `inherited_v15_path` 与 v15 完全一致。∎ 推论：**新组件不引入不可回退的耦合**，v16 始终可沿 v15→…→v6 退化链退回。

## 7. 已知风险与失效模式

1. **支撑图幻觉**：遮挡或透明/反光物体使位姿估计错误，支撑图随之错误，证书在错误图上自洽。缓解：`U_pos` 保守折减、多视角/触觉复核、支撑图变更即停。
2. **瞬态支撑转移漏证**：抬升/放置期间支撑责任在桌面与夹爪间切换，若窗口未覆盖会短暂"无支撑"。缓解：显式 `support_transfer_certificate`、交接期降低速度与扰动、失败即停。
3. **同伦枚举爆炸**：物体与支撑图组合多时 `M` 迅速增长。缓解：按下界代价剪枝、分层骨架、离线缓存、显式报告 `η`。
4. **相对完备性被误读为绝对完备**：外部把"类内无解"当成"物理无解"。缓解：强制输出 `η/δ/assumptions`、日志标注、接口层拒绝裸"无解"。
5. **摩擦系数漂移**：桌面材质、油污、负载改变使 `μ` 区间失配，支撑余量虚高。缓解：在线摩擦辨识、区间化 `μ`、保守下限、漂移检测。
6. **走廊过窄导致活性塌缩**：`r` 太小、`τ_tr` 太紧时几乎每帧都退到停靠。缓解：自适应 `r`、分层走廊、把假停靠计入任务预算。
7. **技能目录不完整**：某些接触段无法投影到 v15 技能，引理 133 失效。缓解：部署前 100% 投影校验、未覆盖段直接禁止、扩展目录后重证。
8. **支撑图变化后沿用旧覆盖**：桌面被移动/新增物体后仍用旧 `Cov`，导致错误的"无解"或漏解。缓解：图变更触发 HSC 重建（引理 139），否则退回单类。
9. **计算尖峰与遮挡同相**：越难的场景越需要重规划，且感知更差。缓解：复用 v13 anytime 前缀、预留 `B_corr`、优先返回短前缀而非长走廊。
10. **相邻物体耦合的级联倾倒**：一个物体被推动后触发另一物体的支撑失效。缓解：支撑图闭包检查、级联传播的保守上界、必要时冻结邻域。

## 8. 本轮最大风险

**一句话**：整套走廊证书以"位姿与支撑图信念正确"为前提，而桌面最危险的失效恰恰是**信念已经错了、证书却还在错误的支撑图上处处成立**——系统会沿着一条逐段可证、始终"留在走廊内"的路径，把杯子稳稳地推下桌。
