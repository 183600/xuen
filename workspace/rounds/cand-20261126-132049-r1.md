## 1. 两个灵感的第一性原理

### 灵感 1 ·「强化学习」→ 要学的不是「怎么动」，而是「什么时候信谁、什么时候认输」

**直觉**：基座 VLA + IP-09 伺服已经决定连续动作；真正还靠人手写死的，是**离散决策层**——继续跑 / 保持等待 / 重定位 / 重抓 / 换原语 / 主动探测 / 向人让步。这个决策空间只有 7 个左右的动作、事件驱动、尺度小，正是离线 RL 样本效率最高、也最容易做安全兜底的地方。所以本轮**不对基座做端到端 RL**（步数预算、评测规则、接口冻结三重不允许），只学一个挂在冻结策略之上的**介入元控制器**；第 3 轮的规则优先级正好充当行为策略（behavior policy），RL 只学它的**残差修正**。

**严谨定义**：把介入决策建成**半马尔可夫决策过程（semi-MDP, U19）**——状态 = 场景图摘要（IP-13）+ 当前路标相位 + 不确定度 + 剩余步数预算；动作 = 7 元介入集；奖励 = 成功终端项 + **势函数化的步骤成本**（L17）+ 硬约束由盾外部强制（不入奖励，见灵感 2）。学习用离线保守 RL（CQL/IQL 类），部署前必须过**悲观 off-policy 评估（OPE）门禁**（L15）。三条纪律：①只用离线数据，竞赛环内禁止在线试错；②价值只在行为策略覆盖得到的状态上可信，覆盖外退回规则优先级；③语料变多 ≠ 可训变多，先做任务/物体级重叠审计（F2）。

**为什么现在才做**：第 1–3 轮没有失败富集语料时，学介入价值是空中楼阁；F1 的 110 项 G1 Dex1 语料 + IP-06 的成功/失败标注 + 事后重标注（HER），第一次让「失败→正样本」的转换有了原料。RL 在本轮的正确位置是**数据闭环的下游**，不是替代基座。

### 灵感 2 ·「伦理与合规」→ 把「不许做的事」变成硬约束，而不是奖励里的一项

**直觉**：一旦把安全/合规写成奖励惩罚项，优化器就会在边际上拿它换成功率——这是 RL 的规格博弈（specification gaming）顽疾，不是调参能解决的。伦理与合规的正确工程形态是**可行动作集**：先由规则手册 + 机器人物理极限 + 评测 API 契约编译出 `A_safe(s)`，再由盾（shield）否决越界动作，盾的每次否决都写审计日志；价值函数只能在合法集合内排序。这样「安全」与「得分」在结构上不可交换。

**严谨定义**：①**安全盾（U20）**：`π_sh(s)=argmax_{a∈A_safe(s)} Q̂(s,a)`，`A_safe(s)` 由硬约束 C1..Ck 生成，且 `YIELD` 恒在集合内；②**合规溯源台账（U21）**：每个外部资产（权重/数据/许可证/规则条款/允许用途/证据）在进入代码库前必须登记，授权不明者默认禁用（WMA-0 的 NOASSERTION 即是实例）；③**奖励规范面（U22）**：枚举「能提高分数但违反任务意图」的行为（提前终止、扫掠式搬运、读仿真真值、步数刷分、碰撞取巧），用红队探针在代理评测上先打一遍。合规不只是清单，是**可被验证的约束系统**。

## 2. 研究问题（新增 Q13–Q16，接第 1–3 轮 Q1–Q12）

- **Q13（离线介入价值能否胜过规则优先级）**：在行为策略覆盖内，离线保守 RL 学到的介入价值，能否在步数预算约束下严格优于第 3 轮的固定优先级？悲观 OPE 的置信下界能否作为部署门禁？（E634）
- **Q14（硬约束的边界与活性代价）**：人机接触、关节/力矩/工作空间、观测→动作 API 契约这三类硬约束如何编译成 `A_safe(s)`？盾把「合法但无用」的原地等待挡出来时，活性（liveness）损失多大？（E635）
- **Q15（合规能否构造即审计）**：权重/数据/规则的溯源台账能否做到 100% 覆盖、授权不明零启用，并把训练-评测污染压到可声明范围？能否一次关闭 Q3/Q4/Q9 的开放合规问题？（E637）
- **Q16（评测器能否先被红队）**：代理评测与最终策略如何系统地红队，保证 0 个「刷分但违规」的行为被接受？（E636）

## 3. 设计原则（新增 P13–P16，接第 1–3 轮 P1–P12）

- **P13（硬约束不入奖励）**：安全与合规是 `A_safe(s)` 的准入条件，绝不写成奖励项；任何「用分数换安全」的设计直接否决。
- **P14（离线优先、悲观门禁）**：学习型控制器只从离线数据训练；部署前必须过悲观 OPE 门禁（改善下界 > 0）且通过覆盖检查；竞赛环内禁止在线 RL 探索。
- **P15（无台账不上线）**：任何外部权重/数据集/规则解释，未在溯源台账登记且授权明确前，不得进入提交物；不确定即按「不可用」处理。
- **P16（先红队后提交）**：评测器与策略都要先过规格博弈红队；红队发现未修复的越界行为，是提交的硬阻断项（与 P13 同级）。

## 4. 清单处置（深化 / 修剪 / 新增）

- **深化**：IP-02（固定优先级 → 学到的介入价值 + 盾；规则优先级保留为 Level-2.0 退化，不再是一等决策器）；IP-12（失败课程升级为「失败回放 + 事后重标注」数据工厂，供 IP-16）；IP-06（新增污染审计、规格博弈红队套件、安全切片）；IP-10（探测 vs rollout 的步数账保留，价值估计改由 IP-16 复用）；IP-03（审计日志扩到盾的每次覆盖决策）；IP-13（场景图摘要成为 U19 的状态输入）。
- **新增**：IP-16 RecoveryValue（离线保守 RL 介入价值，P1）；IP-17 ComplianceShield + ProvenanceLedger（规则编译 + 安全盾 + 溯源台账 + 红队，P0 流程门禁）。

- **MVP 不变**：IP-06 + IP-02 + IP-09 + IP-03 + 通用基线；**IP-17 从第 0 天起作为流程门禁并行执行**（零模型、近零成本，先把「不可交换的安全/合规」立起来）；**IP-16 为 MVP 后的学习型扩展**。

## 5. 本轮最大风险

**盾与离线价值的耦合失效**：离线 Q 在覆盖不足处乐观高估，盾又频繁否决「非法但高价值」的动作，策略可能退化成在「合法但无用」的等待/微调里空转——分数丢了，还披着「安全」的外衣。对冲：①悲观 OPE 门禁 + 覆盖检查，覆盖外一律退回规则优先级（P14/Level-2.0）；②盾加**反停滞计时器**（连续等待超 `T_live` 强制 RELOCALIZE），把活性当一等指标测（E635）；③奖励塑形只许势函数形式（L17），非势奖励一律视为刷分面禁入。

## 6. 下一轮迭代计划（深化与修剪，不推倒重来）

- **深化**：IP-17 的「规则手册 → 约束」编译器与溯源台账 schema（先把 P0 门禁跑通，再谈模型）；IP-16 的介入半 MDP 状态编码与离线数据集切分（含污染审计后的 110→可用子集）；IP-06 的红队探针清单；IP-02 的 learner↔rule 双轨切换开销实测。

## 3. 新增 IP 详述

### IP-16 · RecoveryValue 离线介入价值（P1，新）

- **动机**：第 3 轮把「出事怎么办」写成了固定优先级（接触让步 > 重定位 > 重抓 > 换原语）。但优先级是**状态无关**的：同一操作在 uncertain 区、步数将尽、目标已漂移三种状态下，最优介入显然不同。RL 的正确落点不是基座，而是这个 7 元、事件驱动的决策层；110 项 G1 Dex1 语料（F1）+ IP-12 的失败重标注第一次提供了训练原料。
- **与现有方案差异**：不训新基座、不做在线探索、不改观测→动作接口；只训练一个挂载在冻结策略上的**介入元控制器**，规则优先级作为行为策略与兜底（同源数据、同源动作集，切换无接口成本）。
- **技术可行性**：中高。动作空间小、状态低维；离线数据有成功/失败标注；用 CQL/IQL 类保守离线 RL 抑制 OOD 高估；用 FQE/DR 做 OPE；HER 把「没完成原目标但完成了子目标」的失败转成正样本。风险在奖励定义与覆盖，不在模型容量。
- **资源**：数据=G1 Dex1 110 项（先污染审计后用）+ IP-06 32 项代理回放 + 自采失败片段；算力=单卡级（低维 Q 网络）；接口=无新增字段（内部件）。
- **落地步骤**：①U19 状态/动作/奖励 schema（势函数化步骤成本）；②IP-12 生成「失败回放 + HER 重标注」数据集并做任务/物体级重叠切分；③保守离线训练 + OPE（FQE/DR）置信下界；④过门禁才接 IP-02（learned↔rule 双轨 + Level-2.0 退化）；⑤E634 代理闭环 A/B。
- **风险**：覆盖外乐观高估（悲观正则 + OPE 门禁 + 退化）；奖励塑形诱发刷分（只许势函数形式，L17）；语料污染（F2：110≠32，先审计再训）。

### IP-17 · ComplianceShield + ProvenanceLedger（P0，新，流程门禁）

- **动机**：安全/合规一旦进奖励就会被优化器交易；而竞赛还存在规格博弈面（提前终止、扫掠搬运、读真值、步数刷分、碰撞取巧）。需要一个**与价值解耦的硬约束层**，把规则手册 + 机器人物理极限 + 观测→动作 API 契约编译成可行动作集，并对所有外部资产做授权溯源。
- **与现有方案差异**：不是又一个 reward penalty，而是运行时的 admissible-set 投影；不是文档清单，而是 CI 门禁 + 可回放审计日志。与 IP-02/IP-15 的「让步」直接耦合：接触类事件只会把集合收缩到 `{YIELD}`。
- **技术可行性**：高。规则级约束 + 断言式检查，零训练；盾只做集合过滤与优先级重排，计算量近零；台账是工程 schema + CI 脚本；红队是探针套件。
- **资源**：近零算力；人力在规则条款到约束的翻译与红队用例设计；不依赖 WMA-0（授权不明者默认不启用）。
- **落地步骤**：①把已知规则条款编译成 C1..Ck（人机接触→YIELD；关节/力矩/工作空间；禁止读仿真真值；仅 observation→action）；②`A_safe(s)` 生成器 + 盾 + 反停滞计时器（连续 HOLD 超 `T_live` 强制 RELOCALIZE）；③溯源台账 schema 与 CI 门禁（授权不明零启用，WMA-0 为反例样本）；④IP-06 规格博弈红队探针；⑤E635/E636/E637。
- **风险**：盾导致停滞（反停滞 + 活性指标）；约束过度收缩损害分数（E635 量化覆盖与活性代价）；规则理解错误（台账记录条款出处，开放问题挂 Q3/Q4/Q9）；红队盲区（外部评审 + 探针迭代）。

## 5. 符号与定义（新增 U19–U22；U1–U18 沿用第 1–3 轮）

- **定义 U19（介入半马尔可夫决策过程）**：`M_I = (S, A, P, R, γ, τ)`；`s ∈ S` =（IP-13 场景图摘要、当前路标相位、不确定度、剩余步数预算）；`A = {CONTINUE, HOLD, RELOCALIZE, REGRASP, SWITCH, PROBE, YIELD}`；决策在介入事件时刻发生（半 MDP，`τ` 为决策间隔）；奖励 `R = 1[success] + γΦ(s') − Φ(s) − c_step·steps`，`Φ` 为剩余预算势函数。
- **定义 U20（动作安全集与盾）**：`A_safe(s) ⊆ A` 由硬约束 C1..Ck 生成；盾 `π_sh(s,a)=a` 若 `a∈A_safe(s)`，否则 `argmax_{a'∈A_safe(s)} Q̂(s,a')` 并记 `override` 事件；约定 `YIELD ∈ A_safe(s)` 恒成立（保证非空）；反停滞：连续 `HOLD` 超 `T_live` 时强制 `RELOCALIZE`。
- **定义 U21（合规溯源台账）**：`L = {(asset_id, type, license, rule_clause, permitted_use, evidence, review_date)}`；门禁规则：`permitted_use ≠ "cleared"` 的资产不得进入提交物（授权不明 = 禁用）。
- **定义 U22（奖励规范面 / 规格博弈探针集）**：`G = {(probe, expected_violation)}`，探针覆盖提前终止、扫掠搬运、读仿真真值、步数刷分、碰撞取巧等；红队通过 ⇔ 所有 `probe` 均被评测器/盾判为违规或不可得分。

ACTIONS = ["CONTINUE", "HOLD", "RELOCALIZE", "REGRASP", "SWITCH", "PROBE", "YIELD"]

## 7. 推导（新增引理 L14–L17；L1–L13 沿用第 1–3 轮）

**引理 L14（固定优先级的最优条件与优先级遗憾）** 设 `Q*` 为 U19 的真实介入价值，`π_rule` 为固定优先级策略。则 `π_rule` 最优 ⇔ 对所有可达 `s`，优先序与 `argmax_a Q*(s,a)` 一致；否则其**优先级遗憾** `Reg_rule = E_s[ max_a Q*(s,a) − Q*(s, π_rule(s)) ] ≥ 0`。若学到 `Q̂` 满足 `‖Q̂−Q*‖∞ ≤ ε`，则贪心策略的遗憾 `≤ 2ε`（有限 MDP 模拟引理）。⇒ RL 能否胜过规则优先级，取决于数据中是否存在「价值排序 ≠ 优先序」的状态（覆盖条件），而不是模型大小；这也是 E634 要先做 OPE/覆盖门禁的理论依据。∎

**引理 L15（悲观 OPE 门禁的改进保证）** 在行为策略支持（concentrability/coverage）成立、且 OPE 估计器给出保守下界 `LCB` 时，仅当 `LCB(J(π̂) − J(π_b)) > 0` 才部署，则真实改善为正的概率 ≥ 1−δ；反之，在 `(s,a)` 缺乏行为策略支持时，离线数据无法辨识该处的反事实价值（无有限样本保证，Kumar et al. 2020；Thomas & Brunskill 2016）。⇒ 「离线优先 + 悲观门禁」不是保守主义，而是离线 RL 可部署性的**必要条件**；覆盖外必须退回规则优先级（Level-2.0）。∎

**引理 L16（盾的安全不变式与活性代价）** 设盾每次执行 `a_exec = π_sh(s, a_prop)`；若（i）对任意 `s`，`A_safe(s) ≠ ∅`（YIELD 恒在），（ii）`A_safe` 由硬约束构造且其中动作均满足 C1..Ck，（iii）盾对所有 `a∉A_safe(s)` 覆盖。则对任意策略与任意扰动，执行动作序列恒满足 C1..Ck（对步数归纳）。活性：设覆盖率为 `ρ`，则最多 `ρT` 步被改道；但**安全不蕴含进展**——若无反停滞，`YIELD` 可无限重选，造成「合法空转」。故必须加 `T_live` 反停滞，把「进展」作为与安全并列的验收指标（E635）。⇒ 盾只保证不越界，不保证不摆烂。∎

**引理 L17（势函数塑形不改变最优策略）** 若 `R'(s,a,s') = R(s,a,s') + γΦ(s') − Φ(s)`，则对任意 `Φ`，最优策略集合不变（Ng, Harada & Russell 1999）。⇒ 用 `Φ(s)=剩余步数预算` 编码步骤成本是**策略不变**的安全塑形；任何非势形式 bonus（如「提前完成一次性奖励」「移动物体计数奖励」「速度奖励」）都会改变最优解，属于 U22 规格博弈面，必须禁入奖励。⇒ 这是 RL 与合规之间的关键桥梁：不是所有奖励工程都危险，但危险的那一类恰好是「看起来最有效」的那一类。∎
