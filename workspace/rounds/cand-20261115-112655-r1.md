# 第 5 轮（灵感循环第 5 轮；本轮灵感：「分层规划」×「安全对齐」）

> **基线**：第 4 轮 InstructGauge-WR（IP-328–333；定义 448–467；引理 59–62；实验 E457–E472）。LeanGauge / MODGAUGE / ToolGauge / InstructGauge 骨架继续继承不变。
> 本轮纪律：**结构升级 + 严格退化**。分层规划把「块长 K」升级为「跨层契约」；安全对齐把「硬约束」升级为「分层的可接受行为集 + 风险预算」。二者都是可选增强：关掉层次 ⇒ 退回扁平 InstructGauge-WR；关掉对齐监控 ⇒ 退回静态约束。

## 0. 直觉与动机

**灵感 1（分层规划 → 安全不是一个层的事，而是层与层之间的契约）**
直觉：人类修盲区不是「一个策略从头干到尾」，而是先决定「先修哪个区」（mission），再决定「用擦、刮还是补光」（task），最后才落到「这一块动作怎么走」（motion）。分层的收益是把长程问题变短、把复用变多；但代价是**表达意图的层和执行物理的层被拉开了距离**。一句「把这块清干净」在 mission 层是一个目标，在 motion 层却对应无数条轨迹，其中有些轨迹「看起来干净」但已经划伤表面。于是安全不能只在最底层做一个 `if`，也不能只在高层的奖励里写一句「别划伤」；它必须是层与层之间可检查的**契约**：上层只承诺它能被下层兑现的安全，下层只执行它拿得出证书的动作。这正是 assume-guarantee 的思路，只不过这里的 guarantee 同时包含「行为被细化」与「风险不超支」。

**灵感 2（安全对齐 → 对齐不是把 reward 调对，而是让每层只承诺它能兑现的安全）**
直觉：把「安全对齐」理解成训练一个更好的偏好模型，容易忽略一个结构性事实：在分层系统里，**每一层都有自己的「可接受行为集」**，而人类的价值与约束通常只在最上层被表达。如果层与层之间没有对齐，高层可以合法地选择一个「抽象上正确、具体上有害」的动作，低层也可以在一个局部最优里把风险预算花光。我要的对齐不是「一个全局 reward 对齐所有层」，而是三层各自的 `Safe_ℓ` 与一个**单向保守的抽象关系**：抽象说安全，具体必须安全；抽象说可接受，具体的行为必须仍然是人类授权的那一类行为（细化关系），而不是偷换成另一种只满足代理指标的 behavior。偏好模型只负责「在安全集合里选哪个」，并对自己的不确定性负责——不确定就升级问人，而不是自信地优化一个可能错的目标。

**灵感 3（耦合 → 层次制造了「抽象的善」与「具体的害」之间的缝）**
直觉：分层 × 对齐最危险的耦合是**风险预算的洗白**：mission 把 0.05 的风险预算分给 5 个 task，每个 task 又分给若干 chunk；如果每一层都只检查「我自己没超」，而分配时可以四舍五入、或把不可逆动作的未用预算退回，那么总风险会被重复计算成「看起来更便宜」。第二重耦合是**抽象的乐观**：为了可解，抽象必然丢掉一些物理细节（力、接触模式、表面粗糙度）；如果丢掉细节后的 `Safe_ℓ` 比具体 `Safe_{ℓ-1}` 更宽，那么分层 shield 会为一条具体不安全的轨迹发证书。

一个最小的反例（产物区引理 70 会正式化）：mission 层只区分「干净 / 脏」，具体层还区分「干净但已划伤」。若抽象把「干净但已划伤」映射成「干净」，而 mission 的 `Safe_1` 允许「干净」，则 mission shield 放行、task 层也放行、motion 层只检查「是否干净」——每一层局部都正确，组合起来却违反了具体的 `Safe_0`。这说明**单调安全抽象**不是装饰，而是分层安全能够组合的必要条件。

解法是四根结构柱子：**单调安全抽象**（抽象只能更保守，不能更宽松）、**风险预算守恒**（分配只减不增，不可逆后不得回流）、**契约守护细化**（细化失败必须反馈并消耗重规划预算，不能静默换一个能过的动作），以及**对齐不确定性升级**（偏好后验歧义或分布漂移超过阈值时，宁可停下来问人，也不把「模型觉得好」当成「人觉得好」）。

## 1. 研究问题（本轮要回答什么）

- **Q1（垂直组合）**：每层局部安全加上细化契约，能否推出具体执行安全？「抽象的善、具体的害」的反例结构是什么，需要什么条件才能堵住？
- **Q2（水平对齐）**：在偏好模型有误差、分布会漂移时，如何量化「对齐差距」并决定何时升级问人？安全保证与对齐保证能否分开陈述？
- **Q3（预算与分块）**：风险预算如何沿层次分配而不被「洗白」？块长 `K` 如何由剩余预算与不可逆性决定，而不是继续用固定 `drift_bound`？
- **Q4（退化）**：分层/对齐的任一组件不可用时，能否逐级退回 InstructGauge-WR / InstructGauge v3 / ToolGauge，且轨迹与证书严格等价？

## 2. 四条设计原则（雏形，正式化见产物区定义 468–483）

**P1 单调安全抽象（Monotone Safety Abstraction）**
抽象关系 `α_ℓ` 必须满足 `α_ℓ^{-1}(Safe_ℓ) ⊆ Safe_{ℓ-1}`：凡是抽象层认为安全的 concrete state，具体层也必须安全。允许抽象因为丢信息而**变窄**，绝不允许它因为「好解」而变宽。这是垂直组合定理的唯一结构性前提。

**P2 风险预算守恒（Risk-Budget Conservation）**
风险是守恒货币：`Σ b_child ≤ b_parent`；执行只消耗；可逆动作的余额只能退回直接父层；跨不可逆动作后，未用预算**作废**、不得回流。任何一层都不能通过「换一个更乐观的估计」来凭空造预算。

**P3 契约守护细化（Contract-Guarded Refinement）**
每个抽象动作带 `(Pre, Post, b, Rev)` 契约。细化器只能返回「满足契约的实现」或 `⊥`，不能返回一个只满足代理指标的替代品；`⊥` 必须带着失败原因回到上层，并消耗一个有限的重规划令牌。

**P4 对齐不确定性升级（Alignment-Uncertainty Escalation）**
当偏好后验熵、模型分歧、或分布漂移统计量超过预注册阈值，或「问人」的期望信息价值大于其成本时，系统进入 `HumanConfirm` 或 `SafeHold`，而不是继续优化一个可能错位的目标。

## 3. 与基线的接口（如何退化）

- 抽象关系不可证 / 关闭层次 ⇒ 扁平 InstructGauge-WR，`K` 由 v4 的 `drift_bound` 与不可逆屏障决定；
- 风险账本不可用 ⇒ 用 v4 的固定 `K` 与后置 `SpatialCert` 检查；
- 契约细化失败 ⇒ 当前抽象动作退化为 `K=1` + 人工确认（等价于 ToolGauge 逐步执行）；
- 偏好模型不可用 ⇒ 使用默认保守目标（最大化盲区覆盖、最小化不可逆接触），与 v4 目标一致；
- 对齐监控关闭 ⇒ 不做升级，只保留静态约束（v4 行为）；
- 所有增强失效 ⇒ InstructGauge-WR ⇒ InstructGauge v3 ⇒ ToolGauge ⇒ LeanGauge ⇒ MODGAUGE。

## 4. 预期贡献

1. 一个**分层安全契约**：用单调安全抽象 + 契约细化，把「每层局部安全」升级为可证明的「垂直组合安全」，并给出抽象乐观导致组合失效的分离反例；
2. 一个**风险预算账本**：把 mission/task/chunk 的风险分配变成守恒货币，直接驱动块长 `K` 的选择，堵住「每层都没超、总和却超了」的洗白路径；
3. 一个**对齐差距分解与升级策略**：把安全保证（可证明）与对齐保证（可估计、可升级）明确分开，给出 `Δ_abs + Δ_pref + Δ_est` 的可证伪分解；
4. 一条完整可证伪路径：E473–E488 覆盖垂直组合、预算守恒、对齐差距、升级校准、预算可行块长、长程修复、退化等价、对抗规格博弈与 50Hz 时序。

## 5. 本轮最大风险

**一句话**：整轮的可靠性押在「抽象关系在每个接缝上都真的更保守」这一条上——只要有一个接缝为了可解性偷偷把 `Safe_ℓ` 放大，分层 shield 就会给一条具体不安全的轨迹发证书，而风险账本还会让这次越权看起来「预算内」。

## 2. 形式化定义（要点）

**定义 468（分层安全对齐决策过程 HSADP）**
```
H = (S_0, S_1, S_2, A_0, A_1, A_2, α_1, α_2, P, Safe_0, Safe_1, Safe_2, B_2, U_h, γ)
```
其中 `S_0` 是 v4 的具体执行状态，`S_1` 是任务状态（技能、进度、资源），`S_2` 是 mission 状态（盲区集合、剩余不确定质量、剩余预算）；`Safe_ℓ = Hard_ℓ ∩ PrefAcceptable_ℓ`，`Hard_0` 继承 v4 的 CVC；`P` 是分层转移核，低层转移必须在高层抽象下可模拟。

**定义 469（安全模拟关系 `R_ℓ`）**
`R_ℓ ⊆ S_ℓ × S_{ℓ-1}` 称为安全模拟，若：
1. 初始状态满足 `(α_ℓ(s_{ℓ-1}^0), s_{ℓ-1}^0) ∈ R_ℓ`；
2. 对任意 `(s_ℓ, s_{ℓ-1}) ∈ R_ℓ` 与具体转移 `s_{ℓ-1} →^{a_{ℓ-1}} s'_{ℓ-1}`，存在抽象转移 `s_ℓ →^{a_ℓ} s'_ℓ`，使得 `(s'_ℓ, s'_{ℓ-1}) ∈ R_ℓ`，且 `a_{ℓ-1}` 是 `a_ℓ` 的合法细化。

**定义 470（单调安全抽象 MSA）**
`R_ℓ` 满足
```
∀ s_{ℓ-1} ∈ S_{ℓ-1}:  α_ℓ(s_{ℓ-1}) ∈ Safe_ℓ  ⇒  s_{ℓ-1} ∈ Safe_{ℓ-1}
```
即 `α_ℓ^{-1}(Safe_ℓ) ⊆ Safe_{ℓ-1}`。允许抽象丢掉细节后 `Safe_ℓ` 变窄，禁止其变宽。**这是垂直安全组合的结构性前提，不是实现细节。**

**定义 471（抽象动作契约与细化）**
抽象动作 `a ∈ A_ℓ` 的契约为 `K(a)=(Pre_a, Post_a, b_a, Rev_a)`，`Pre_a, Post_a ⊆ S_ℓ`，`b_a ≥ 0`，`Rev_a ∈ {R0, R1}`（`R0` 不可逆）。具体/下层实现 `κ ∈ A_{ℓ-1}` 满足 `κ ⊑ K(a)` 当且仅当：
```
guard:   执行 κ 时必在 Pre_a 内，且 κ 的入口守卫强于 Pre_a
post:    κ 的所有终止状态落在 Post_a 内
budget:  risk_bound(κ) ≤ b_a
rev:     Rev_κ ≤ Rev_a   （可逆性不放大；R0 只能由 R0 实现）
```

**定义 472（对齐证书 `AlignCert`）**
分层计划 `Π=(a_2; {a_1^i}; {κ_0^{i,j}})` 的对齐证书是一个四元组
```
AlignCert(Π) = (R_1, R_2, obligation_log, ledger)
```
其中 `obligation_log` 记录每条 `κ ⊑ K(a)` 的检查结果，`ledger` 是风险预算账本。证书有效当且仅当四条义务同时成立：`R_ℓ` 为 MSA、每条细化满足契约、预算守恒、偏好差距 `Δ_align(Π) ≤ ε_align`。

**定义 473（风险预算账本与守恒律）**
账本状态 `(B_2, spent, remaining, tokens)`，操作：
```
alloc(parent, children):   Σ_j b_j ≤ parent            （只减不增，禁止铸币）
spend(r̂):                 spent += r̂; remaining -= r̂
retire(irreversible):      若 Rev=R0，未用余额置 0，不得回流
return(reversible):        可逆动作的未用余额只能退给直接父层
```
不变量：`spent + Σ_leaves remaining ≤ B_2`；任何时刻 `remaining ≥ 0`。**不可逆动作后的 `retire` 是防止同一笔预算被后续计划「重新花一次」的关键。**

**定义 474（预算可行块长）**
对候选块长 `K`、每步风险上界 `r_max`、剩余预算 `b`、安全余量 `η`：
```
K_max(b) = ⌊(b − η) / r_max⌋
K = min(K_plan, K_max(b), K_contract)
```
若 `Rev=R0`，强制 `K=1`（继承第 3 轮不可逆屏障）；若 `K<1`，返回 `⊥` 并升级/`SafeHold`，不得以 `K=1` 偷偷超预算。

**定义 475（对齐差距及其分解）**
```
Δ_align(Π) = sup_{τ ∈ Beh(Π)} (U_h(τ) − Û(τ))
```
在给定分解 `U_h → U_2 → U_pref → Û`（mission 代理 → 偏好模型 → 估计器）下：
```
Δ_align ≤ Δ_abs + Δ_pref + Δ_est
Δ_abs  = sup_τ (U_h(τ) − U_2(α_2(τ)))
Δ_pref = sup_τ (U_2(τ) − U_pref(τ))
Δ_est  = sup_τ (U_pref(τ) − Û(τ))
```
注意：**安全是证明，对齐是估计**。`Δ_abs` 不受 MSA 保证，必须显式测量；这正是升级策略存在的理由。

**定义 476（升级策略与 VOI）**
```
should_escalate(s) ⇔ H(post) > τ_H
                  ∨ drift_stat(s) > τ_shift
                  ∨ VOI(s) > c_q
```
其中 `VOI(s) = E_{q~Q}[max_a Û(a|q)] − max_a E_q[Û(a)]` 是问人查询 `q` 的期望信息价值。升级动作是 `HumanConfirm` 或 `SafeHold`（冻结块长并保持接地）。

**定义 477（分层屏蔽器）**
```
Shield_ℓ(s, a) = 1  ⇔  a ∈ A_ℓ ∧ s ∈ Pre_a ∧ δ_ℓ(s,a) ⊆ Safe_ℓ
```
`δ_ℓ(s,a)` 是 `a` 在 `ℓ` 层的可达状态集。`Shield_0` 复用 v4 的 `CVC ∧ still_grounded`；`Shield_1/2` 只做抽象层守卫，不替代 L0。

**定义 478（细化失败反馈）**
```
refine(a, b) → (κ, AlignCert) | ⊥_reason
reason ∈ {pre_fail, post_fail, budget_fail, irrev_fail, abs_fail}
```
`⊥` 不得被静默替换成另一个「能过」的动作；它必须回到规划器，并消耗一个重规划令牌。

**定义 479（良基修复测度）**
```
μ = (tokens, remaining_budget, plan_depth)
```
按字典序比较。每次重规划 `tokens ← tokens−1`；每次细化 `plan_depth ← plan_depth−1`；`alloc` 不增加 `remaining`。`tokens` 有限，故修复循环不可能无限；`μ` 无法下降时强制升级。

**定义 480（分布漂移与对齐监控）**
用滑动窗口的嵌入距离/残差分布检验得到 `drift_stat(s)`；当 `drift_stat > τ_shift` 时，`Δ_pref` 的置信上界失效，必须重新校准偏好模型或升级。监控器只读，不进入 50Hz 主路径。

**定义 481（对齐压力测试）**
一组预先注册的代理指标博弈用例 `T_align = {(U_h, proxy, exploit)}`：每个用例给出一个「在代理上更优、在真实效用上更差」的行为，用来检验 `Δ_abs` 是否被低估。该集合在实验前冻结，防止事后挑选。

**定义 482（人工确认与安全保持）**
`HumanConfirm` 返回三种结果：`approve`（继续，预算与证书不变）、`revise`（给出新偏好/新约束，重新校准后重规划）、`abort`（进入 `SafeHold`，只执行可逆的退出动作）。`SafeHold` 期间 `K=1`，且只允许 `Rev=R1` 的动作。

**定义 483（严格退化映射）**
若关闭层次（`S_2=S_1=S_0`，`α_ℓ=id`，`Safe_ℓ=S_0`，`B_2=∞`，`tokens=0`，`AlignMonitor=off`），AlignGauge-H 的主循环退化为 `InstructGauge_WR_round`，`instructgauge_wr` 的 `iota/H/K` 参数与原 v4 逐一相同。该映射是后续退化等价测试的规范定义。

## 3. 关键算法骨架

```python
class RiskBudgetLedger:
    def __init__(self, B2, replan_tokens=4):
        self.B2 = B2
        self.remaining = B2
        self.spent = 0.0
        self.tokens = replan_tokens

    def alloc(self, parent_b, child_bs):
        if sum(child_bs) > parent_b + 1e-12:
            raise BudgetViolation("mint attempt: sum(child) > parent")
        return child_bs

    def chunk_len(self, b, r_max, eta, rev, k_plan):
        if rev == "R0":
            return 1                      # 不可逆屏障，继承 v3
        if r_max <= 0:
            return k_plan
        k = min(k_plan, int((b - eta) / r_max))
        return max(k, 0)                  # 0 ⇒ 升级/ SafeHold

    def spend(self, r_hat, irreversible=False):
        self.remaining -= r_hat
        self.spent += r_hat
        if irreversible:
            self.remaining = min(self.remaining, 0.0)  # 余额作废，不回流
        return self.remaining >= 0.0

    def replan(self):
        self.tokens -= 1
        return self.tokens >= 0


class SafetyAbstraction:
    def __init__(self, alpha1, alpha2, safe0, safe1, safe2):
        self.alpha1, self.alpha2 = alpha1, alpha2
        self.safe = {0: safe0, 1: safe1, 2: safe2}

    def is_monotone(self, ell, s_abstract, s_concrete):
        """定义 470：抽象安全 ⇒ 具体安全"""
        if self.alpha(s_abstract, ell) in self.safe[ell]:
            return s_concrete in self.safe[ell - 1]
        return True

    def certified_on(self, states_0, states_1, states_2):
        """离线/启动时的抽样证书；任一反例即拒绝整个抽象"""
        for s0, s1, s2 in zip(states_0, states_1, states_2):
            if not self.is_monotone(1, s1, s0):
                return False, (1, s1, s0)
            if not self.is_monotone(2, s2, s1):
                return False, (2, s2, s1)
        return True, None


def certify_refinement(M, a_ell, kappa, R_ell):
    """契约守护细化（定义 471/478）"""
    if not M.shield.entails(kappa.pre, a_ell.pre):
        return None, "pre_fail"
    if not M.shield.entails(kappa.post, a_ell.post):
        return None, "post_fail"
    if kappa.risk_bound > a_ell.b + 1e-12:
        return None, "budget_fail"
    if kappa.rev == "R0" and a_ell.rev != "R0":
        return None, "irrev_fail"
    if not M.abstraction.is_monotone(a_ell.level, a_ell, kappa):
        return None, "abs_fail"
    return AlignCert(R_ell=R_ell, obligation_log=[a_ell.id, kappa.id]), None


def aligngauge_h(M, s, ell=None):
    """L2 → L1 → L0；L0 复用 InstructGauge-WR"""
    s2 = M.alpha2(M.env.state())
    mission = M.mission.propose(
        s2, M.dbox.detect_blind_spot(), M.pref_posterior, M.budget_left(s))

    # 对齐不确定性：宁可停，不硬优化
    if M.alignmon.should_escalate(s2, mission):
        return M.escalate(s2, mission)          # HumanConfirm / SafeHold

    plan2, alloc2 = M.mission.plan(mission, M.ledger.remaining)
    M.ledger.alloc(M.ledger.remaining, list(alloc2.values()))

    for a2 in plan2:
        if not M.shield.shield2(s2, a2):
            return M.escalate(s2, a2, reason="shield2")

        plan1, alloc1 = M.task.refine(a2, alloc2[a2], M.skills)
        cert1, why = M.certifier.certify_plan(plan1, a2, M.R1)
        if cert1 is None:
            # 不静默换动作；消耗令牌或升级
            if not M.ledger.replan():
                return M.escalate(s2, a2, reason=why)
            continue

        for a1 in plan1:
            k = M.ledger.chunk_len(
                alloc1[a1], M.cvc.risk_bound(a1), M.eta, a1.rev,
                M.iac.k_plan(a1))
            if k < 1:
                return M.escalate(s2, a1, reason="budget")
            C = M.v4.instructgauge_wr(M, a1, ell, K_cap=k)
            r_hat = M.risk_meter.estimate(C, M.env.trace())
            if not M.ledger.spend(r_hat,
                                  irreversible=C.crosses_irreversible()):
                return M.safe_hold(s2, reason="over_budget")

    return M.ledger.report()


def aligngauge_h_round(M, obs, audio, tac, depth, det, ell=None):
    """50Hz 主路径：与 v4 相同；分层闭环异步提交"""
    if (not M.hierarchy_enabled) or (not M.abstraction.certified):
        return M.v4.InstructGauge_WR_round(M, obs, audio, tac, depth, det, ell)
    for s in M.dbox.detect_blind_spot():
        if s not in M.inflight:
            M.inflight.add(s)
            spawn_async(aligngauge_h, M, s, ell)
    return M.v4.MODGAUGE_round(M, obs, audio, tac, depth, det)
```

## 4. 推导

**引理 63（垂直安全组合）**
若 (i) 对 `ℓ=1,2`，`R_ℓ` 满足单调安全抽象（定义 470）；(ii) 每层选中的抽象动作都被 `Shield_ℓ` 限制在 `Safe_ℓ` 内；(iii) 每条具体/下层行为都是对应抽象动作的合法细化（定义 469）。则对齐层次执行的任意具体轨迹都停留在 `Safe_0`。
**证明**：对层数归纳。`ℓ=1`：由定义 469 的初始关系，`α_1(s_0^0) ∈ Safe_1`，MSA 给出 `s_0^0 ∈ Safe_0`。设当前 `s_0 ∈ Safe_0` 且 `α_1(s_0) ∈ Safe_1`。任取一条具体转移 `s_0 →^{a_0} s'_0`，它细化某个抽象动作 `a_1`；由 `Shield_1`，`a_1` 的到达状态满足 `α_1(s'_0) ∈ Safe_1`；MSA 给出 `s'_0 ∈ Safe_0`。对 `ℓ=2` 在 `S_1` 上重复同一论证，再把 `Safe_1` 作为 `S_1` 的安全集与 `ℓ=1` 复合。故任意长度轨迹都在 `Safe_0`。`□`

**引理 64（风险预算守恒）**
在定义 473 的四个操作下，任何可达账本状态满足 `spent + Σ_{leaves} remaining ≤ B_2` 且 `remaining ≥ 0`；若 `r_max` 是每步风险的可靠上界且块长服从定义 474，则每个块的实际风险不超过其分配预算。
**证明**：对分配树归纳。`alloc` 只做拆分，子预算和不超过父预算，故叶子和不超过根；`spend` 同时减少 `remaining` 与增加 `spent`，和不变；`return` 只在直接父子间转移，不改变总和；`retire` 把不可逆分支的余额置零，只会让总和下降。因此不变量成立。块级风险由 `K ≤ K_max(b)` 得 `K·r_max ≤ b−η ≤ b`，相加即得。`□`

**引理 65（预算可行块长的最大性）**
对固定 `b, η, r_max > 0`，若 `K ≤ ⌊(b−η)/r_max⌋`，则最坏情况下 `K` 步风险 `K·r_max ≤ b−η`；若 `K > ⌊(b−η)/r_max⌋`，存在每步风险取到 `r_max` 的实现使 `K·r_max > b−η`，即预算不可证。`Rev=R0` 时 `K=1` 是定义 474 的硬约束，不是优化结果。
**证明**：由整数除法定义直接得到；后半部分取每步风险 `r_max` 构造即可。`□`

**引理 66（良基修复终止）**
在定义 479 的测度下，任何不触发升级的规划-细化-重规划路径长度有限；若无法继续下降，系统必然升级或进入 `SafeHold`。
**证明**：`tokens` 初始有限且每次重规划严格减一，任何操作都不增加它；因此重规划次数不超过初始令牌数。两次重规划之间，`plan_depth` 在细化中严格下降，`alloc` 不增加 `remaining`。以 `(tokens, remaining, depth)` 字典序为测度，每条不升级的边都使其严格下降；良序集上不存在无限严格下降链。`□`

**引理 67（对齐差距分解）**
在定义 475 的分解下，`Δ_align ≤ Δ_abs + Δ_pref + Δ_est`。
**证明**：对任意轨迹 `τ`，
`U_h(τ) − Û(τ) = [U_h(τ) − U_2(α_2(τ))] + [U_2(α_2(τ)) − U_pref(τ)] + [U_pref(τ) − Û(τ)]`，
逐项取上确界再由三角不等式即得。注意 `Δ_abs` 是抽象保真度，不是安全证书的一部分；MSA 只保证 `Safe` 的包含关系，不保证效用接近。`□`

**引理 68（无静默契约违背）**
若 `refine(a,b)` 返回 `⊥`，则 `a` 不会进入 L0 执行；`aligngauge_h` 只能选择重规划（消耗令牌）或升级。
**证明**：由算法骨架，`cert1 is None` 时立即进入 `replan` 分支，L0 调用只在 `cert1` 非空且 `k≥1` 时发生。`certify_refinement` 对 `pre/post/budget/rev/abs` 任一失败都返回 `⊥`，不存在绕过路径。`□`

**引理 69（严格退化等价）**
在定义 483 的退化参数下，`aligngauge_h_round` 与 `InstructGauge_WR_round` 产生相同轨迹、相同 CVC 证书与相同 `K`。
**证明**：`hierarchy_enabled=false` 时主循环直接调用 v4；预算为无穷时 `K_max=∞`，`K=min(K_plan,K_contract)` 与原 `plan_chunk` 的选择一致；`AlignMonitor` 关闭时无升级；`Shield_0` 复用 v4 的 `CVC ∧ still_grounded`；`certify_plan` 在恒真契约下返回与 v4 相同的证书。逐函数展开即得。`□`

**引理 70（MSA 的必要性 / 分离反例）**
存在一个两层 HSADP，其每层局部屏蔽检查都通过，但组合执行违反 `Safe_0`；而任何满足 MSA 的同类实例都不会出现该反例。因此 MSA 是排除这类组合失效的必要条件。
**证明（反例）**：令
```
S_0 = {dirty, clean, cracked-clean},  Safe_0 = {dirty, clean}
S_1 = {dirty, clean},                Safe_1 = {dirty, clean}
α_1(cracked-clean) = clean,  α_1(clean)=clean,  α_1(dirty)=dirty
```
则 `α_1^{-1}(Safe_1) = S_0 ⊄ Safe_0`，MSA 失败。mission 层选 `clean`，`Safe_1` 放行；task 层细化出「高压擦拭」动作，`Shield_1` 只看到抽象状态 `clean`，放行；L0 的 `CVC` 只检查「是否干净」，不检查表面划伤，于是 `cracked-clean` 被执行。每一层的局部谓词都为真，组合却违反了 `Safe_0`。反之，若把抽象改为 `α_1(cracked-clean)=dirty`，则 `α_1^{-1}(Safe_1) ⊆ Safe_0`，`Shield_1` 不会在 `cracked-clean` 上放行 `clean`，反例被堵住。故 MSA 是必要的，而非装饰。`□`

**推论 71（安全与对齐不可互相替代）**
预算可行但偏好错位的计划（便宜但有害）与偏好对齐但预算不可行的计划（想做但做不起）都可能存在；因此 `AlignCert` 必须同时检查预算义务与 `Δ_align`，任何一方都不能推出另一方。
**证明**：取一个「低成本但划伤表面」的动作与一个「高成本但完全可逆」的动作即可分别构造。安全由 `Safe_0` 与预算约束保证，效用由 `Δ_align` 估计；两者定义在不同空间上，互不蕴含。`□`

## 8. 本轮最大风险

**一句话**：整轮的安全性其实系于「抽象关系在每个接缝上都真的更保守」这一条——只要有一个接缝为了可解性把 `Safe_ℓ` 放大，分层 shield 就会为一条具体不安全的轨迹发证书，而风险账本还会让这次越权看起来「预算内」。
