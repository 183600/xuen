# 第 3 轮迭代（灵感循环 v3：「具身智能大模型」×「决策规划」）—— 从"反应式补救"到"值感知的具身规划"

> 承接 v2（UIP-01′~15：Gazebo 计分神谕 × 实时性 × 模块化）。本轮**不新增传感器、不新增外部模型**，而是换"谁来做决定"：v2 的旗舰 `RHPV-D` 本质是一个**反应式安全网**——每 k 步核验、发现进度被撤回就重做。它能救单步，却回答不了一个终局问题：**"到 episode 结束那一刻，我还剩多少分？"** 两个灵感词把问题重新定义为一个**带截止期、带对抗性撤回、以计分步为权重**的序贯决策问题：「具身智能大模型」提供可预测未来的共享潜空间，「决策规划」在这个潜空间里为终局得分做前瞻。本轮最反直觉的结论（§2.3，合成实验）是：**重排步骤几乎没用；真正的大杠杆是"让已完成的进度变得不可撤回"（降低撤回风险），但盲目承诺会在紧截止期下直接归零——所以必须由规划器按"剩余时间 × 分值"分配承诺。**

## 0. 承接与诊断（v2 → v3）

**本轮不新增外部事实检索**，沿用 v2 于 2026-11-12 核实的事实（32 任务计分点、`human_*`=反向撤回、开环动作块、N 端口隔离、可信度看延迟/动作规律性、单模型为工作假设）。本轮新增的是**形式化、推导与合成实验**，不冒充真机证据。

| v2 已经做对的 | v3 要补的口子 |
|---|---|
| 把 `human_*` 读成"撤回"，用验证-重做兜步骤分 | **G1 近视**：逐子目标贪心推进，没有"当前动作如何影响终局分数"的前瞻；末步分值恒 ≥ 前序步，却不据此分配注意力 |
| 用 Gazebo 做离线计分神谕、造扰动数据 | **G2 算力错配**：ACS 按"阶段"拍脑袋选块长，没有把有限推理算力按"分值 × 不确定性 / 延迟"分配 |
| 用技能图承载 32 任务 | **G3 只把大模型当策略**：没有用它的**世界模型/价值**能力，也没在合规前提下做 test-time deliberation（想清楚再动） |

一句话诊断：**v2 擅长"事后发现被打断"，v3 要擅长"事前安排怎样才不被打断、以及被打断后最坏会损失多少分"。**

## 1. 两个灵感词的解读

### 1.1 具身智能大模型：先给直觉

一个真正有用的具身大模型，不该只是"更大的动作网络"。它更像一个**共享的想象空间**：看到桌子、听懂"把碗叠起来"之后，它能在脑子里回答三个问题——"我下一步大概会做什么"（策略）、"如果我这么做，世界会变成什么样"（世界模型）、"那个样子值多少分/还差哪一步"（价值/进度）。三者共享同一套视觉-语言表征，所以**只需要一个权重文件**：这正是"单模型合规"与"多任务泛化"的交点。所谓 embodied，不是它有身体，而是它的表征**以可执行后果为坐标**。

### 1.2 具身智能大模型：再给严谨定义

设共享编码器 `E_θ` 把观测历史与语言映射到潜状态 `z_t = E_θ(o_{t-Δ:t}, ℓ)`。在同一个 `θ` 上挂四个廉价头：

```
π_θ(a | z_t, g)                 # 动作块先验（option 的条件策略）
W_θ(z_{t+1} | z_t, a, g)        # 潜空间转移（世界模型）
V_θ(A_g=1 | z_t, g)             # 子目标达成/存活的概率
Λ_θ(λ_g | z_t, g)               # 达成后被"撤回"的风险率（hazard）
```

联合训练目标（32 个公开数据集 + v2 的 DRF 合成恢复数据）：

```
L(θ) = E[ -log π_θ(a*|z,g) + β₁·d(z', W_θ(z,a,g)) + β₂·BCE(V_θ, A*) + β₃·(log λ̂ - log λ*)² ]
```

`θ` 只有一个；技能差异由**共享骨干上的门控/低秩适配 + 轻量头**承担，而不是 32 个独立模型。部署时一次前向得到 `(π, V, λ̂)`，`W` 只在需要前瞻时多用几次——这把"大模型"从显存负担变成了**可查询的决策资源**。

### 1.3 决策规划：先给直觉

比赛不是"每一步都做对"的考试，而是**"在一个会把你做完的事偷偷改回去的世界里，让高分步骤在对的时间被完成、并且在终点时仍然完成着"** 的博弈。所以规划的第一目标不是"最快做完"，而是**最大化终局的加权存活分**；第二目标才是"别超时"。计划要能随时被推翻重来（receding horizon），也要能识别"这一步做完就再也改不回去了"（不可逆承诺）——因为不可逆的进度不消耗"撤回风险"。

### 1.4 决策规划：再给严谨定义

把它写成**带对抗撤回的半马尔可夫决策过程（semi-MDP / POMDP）**：

- 计分步 `g_i`，权重 `w_i`，`Σ w_i = 100`；`A_i(T) ∈ {0,1}` 为终局是否仍达成；`S = Σ w_i A_i(T)`，`Success = Π A_i`。
- 决策单元是**选项（option）** `ω = (pre_ω, π_ω, β_ω, Δ_ω)`：一个自终止技能 + 期望耗时 `Δ_ω`。`get_action` 返回的动作块就是"当前选项的首段"。
- 撤回对手 `u ∈ U`：在 `t` 时刻选择把某个已达成 `g_i` 置回未达成。达成后未被撤回的时长服从风险率 `λ_i(t, κ_i)`，`κ_i` 为承诺强度（0=不承诺，1=完全不可逆）。
- 规划目标（含风险与实时约束）：

```
max_π  E[ Σ_i w_i A_i(T) ]  +  α·P(Success)  −  γ·E[latency]  −  ρ·Var(latency)
s.t.   P(latency > B) ≤ ε,      Σ_ω Δ_ω(κ) ≤ T
```

关键结构：**计分是终局判定 ⇒ 越早完成、暴露窗口越长；但完成得越晚，被撤回后越来不及重做。** 这两股力量的对冲，正是 v3 要解的东西。

### 1.5 合流：三句话

**在潜空间里做长视界规划（LRHP）、在物理上做不可逆承诺（IAC）、在动作块边界做最低成本核验（CSR）。** 大模型负责"想象 + 估价 + 提方案"，规划器负责"在截止期内挑一条期望终局分最高的方案"，验证器负责"只在值得的地方花延迟"。

## 2. 严谨推导

### 2.1 终局得分 = 加权存活

在独立风险率、暂不考虑重做的近似下，子目标 `g_i` 于 `τ_i` 达成后存活到 `T` 的概率为

```
P(A_i(T)=1) = exp( −∫_{τ_i}^{T} λ_i(t) dt )  ≜  e^{−Λ_i(τ_i,T)}
E[S] = Σ_i w_i · e^{−Λ_i(τ_i,T)}
```

定义**暴露量** `E = 100 − E[S]`；当 `λ_i` 很小、窗口不长时 `E ≈ Σ_i w_i λ_i (T − τ_i)`。这条式子已经是可操作的：**分值越高、风险率越大、剩余时间越长，暴露越大。**

### 2.2 两个引理

**引理 1（承诺的价值 ∝ 分值 × 剩余时间）。** 若把 `g_i` 的风险率降 `δ`（如"插到底""压紧""拧到位"），则期望分数增益一阶为 `w_i (T − τ_i) δ`。故**承诺应优先给"高权重且已被较早达成"的子目标**——它的暴露窗口最长。反之，一个本来就排在最后、暴露窗口很短的步骤，承诺它的收益有限。

**引理 2（承诺是带截止期的背包，不是越多越好）。** 若给 `g_i` 加承诺需要额外耗时 `c_i`，则可行性要求 `Σ_i (dt_i + c_i·κ_i) ≤ T`。承诺全部子目标可能使总时长越过 `T`，此时 `S = 0`（灾难性），而**部分承诺**可能严格更优：

```
max_{κ_i ∈ [0,1]}  Σ_i w_i · e^{−λ_i(κ_i)(T−τ_i(κ_i))}
s.t.               Σ_i (dt_i + c_i κ_i) ≤ T
```

这是典型的"每秒钟买多少安全性"的背包；解它正是 UIP-18（VOC）与 UIP-20（IAC）的分工。**这也是把"决策规划"从口号变成算法的关键：承诺是一个受截止期约束的资源分配问题。**

**引理 3（核验的 VOI 与评分口径强相关）。** 核验 `g_i` 的价值 ≈ `w_i × P(已撤回但尚未被观测) × P(还来得及重做)`。如果赛制其实是"达成即锁定、撤回不扣步骤分"，则重做对**步骤分**的 VOI 为零；但若锁定规则未知，**优先把进度做成不可逆**在两个口径下都不亏——这给了 v3 一个**对评分口径稳健**的策略。

### 2.3 合成实验：结论与直觉相反（仅用于排序杠杆，不是真机证据）

脚本 `tmp/v3_plan_sim.py` / 结果 `tmp/v3_plan_sim.json`：3 个子目标，权重 30/30/40，达成各 8 s，撤回服从泊松风险率，承诺把风险率 ×0.1、每个多花 3 s，重做时间 6 s 或 20 s，每臂 30,000 episodes。三档时间预算下比较"重排顺序"与"承诺"：

| 场景 | 固定顺序·不承诺 | 高暴露者后置·不承诺 | 只承诺最高 wλ | 全部承诺 |
|---|---|---|---|---|
| R1 宽松 T=40 / 重做 6s | 93.03 / 81.4% | 93.03 / 81.4% | 96.74 / 89.9% | **99.28 / 98.0%** |
| R2 紧张 T=30 / 重做 6s | 92.65 / 80.5% | 92.78 / 80.9% | **97.08 / 90.7%** | **0.00 / 0.0%（超时）** |
| R3 慢重做 T=50 / 重做 20s | 79.79 / 52.0% | 79.72 / 52.1% | 90.18 / 71.5% | **97.70 / 93.6%** |

（单元格 = 平均步骤分 / 成功率；"高暴露者后置"按 `wλ` 升序排，另有"高 `wλ` 前置"臂，三档分别为 92.90/93.02/80.30，与固定顺序的差都在 ±0.6 分内。）

**读法：**
1. **重排顺序单独几乎无效**（三档差异 ≤0.6 分，慢重做档甚至"反着排"略好）——因为撤回是记忆less的，早做完的还能重做；naive 的"降低暴露"排序忽略了"末段不可恢复"的另一半。**v2/v3 若把精力押在"最优顺序"上是错配。**
2. **降低撤回风险（承诺）是数量级更大的杠杆**：R3 平均分 +17.9、成功率 52%→94%。
3. **但承诺必须分配**：R2 里"全承诺"超时直接 0 分，而"只承诺最高 `wλ`"反而最优。**这正是"需要一个规划器"而不是一个阈值规则的实证理由。**

### 2.4 这推翻了什么、没推翻什么

- **推翻**：把"步骤顺序优化"当作主攻方向；以及"验证得越勤越好"（核验有延迟成本，应按 VOI 分配）。
- **没推翻**：v2 的验证-重做仍然必要（它处理"已经不可恢复地晚"的情形）；Gazebo 计分神谕仍是唯一能离线估计 `τ_i, λ_i` 的手段，只是现在它要服务于**规划器**，而不只是给单步打分。

## 3. 瓶颈假设（更新）

- **H1（最高杠杆，换轴）**：终局分数取决于**加权存活**，而非"做过多少步"。最大缺口不是"会不会做"，而是"做完的进度能不能留到终点"。⇒ 承诺/不可逆化 > 重做 > 重排。
- **H2（承诺是受截止期约束的背包）**：承诺降低风险率但消耗时间；最优策略是"按每秒钟的分值增益"分配承诺，而非一刀切。
- **H3（大模型的价值在潜空间前瞻）**：用同一骨干的 `W/V/λ` 头做短视界前瞻，比"更大的动作网络"更省、更稳；但必须防"自己想象自己"的模型误差累积。
- **H4（VOI 决定实时性）**：核验、重规划、承诺都不能均摊；应集中在高 `w` × 高 `λ` × 仍可恢复的步骤上。
- **H5（评分口径未定）**：若最终是"达成即锁定"，v3 的承诺策略仍不亏（不可逆化不伤害成功），但核验-重做的收益会显著缩水；这是需要在手册/真机前先钉死的前提。

## 4. 候选合并 → v3 清单

围绕两词发散 12 个草案，合并后得到 v3：**旗舰 UIP-01‴（PARH-V：计划感知的滚动视界）**，由 **UIP-16 TEB**（一个骨干三头）提供想象与估价、**UIP-17 LRHP**（潜空间滚动规划）做前瞻、**UIP-18 VOC**（价值感知算力分配）管预算、**UIP-20 AUAP+IAC**（对抗撤回 + 不可逆承诺）抓最大杠杆；v2 的 02″/09″/11′/12′/13″/14′/15′ 相应升级，05、08′ 保留。详见产物区。

## 5. 本轮最大风险

**一句话**：整套 v3 押在"撤回风险可建模、且进度会在终局被撤销"的假设上；若真实评分是"达成即锁定"或人为干扰远少于规则文本所示，那么复杂的规划与承诺只会**凭空增加延迟、反而压低成功率与可信度**——即"为一个不在计分函数里的对手造了一台精密的规划器"。

## 1. 旗舰深潜：UIP-01‴ · PARH-V（Plan-Aware Receding-Horizon with Value）

**机制**：每个决策边界维护一份**计分账本** `L = {(w_i, A_i, τ_i, λ̂_i, κ_i)}`，并由三头骨干产生潜状态 `z_t`、世界转移 `W_θ`、价值/风险 `V_θ, Λ_θ`。规划器在 `z` 空间对**选项序列 + 承诺强度**做 anytime 前瞻，目标为终局加权存活分；只执行最优计划的首个选项（≤ 声明块长），下一次 `get_action` 再重规划。

**为什么是升级而非新建**：v2 的 `RHPV-D` 已有 done/ongoing/fail/regressed 状态机；v3 只是把它的"触发条件"从"每 k 步核验"换成"**由计划的价值与风险驱动**"——当规划器判断某步暴露大、且承诺划算时，才在该边界核验/承诺/重做。状态机保留，调度换了大脑。

**关键接口适配**：`action_chunk_size` 在握手时只能声明一次 ⇒ 声明全局 `K_MAX`，每次返回 **≤ K_MAX** 的块；块内对应"一个 option 的首段"，使开环执行天然落在可判定的 option 边界。`reset()` 清空账本与检索缓存。

**与 v2 的差异（三点）**：① 从"单步安全网"到"终局价值优化"；② 从"固定间隔核验"到"VOI 驱动核验"；③ 从"模块化技能头"到"同一骨干上的可规划 option + 承诺旋钮"。

## 2. UIP-16 · TEB（Tri-head Embodied Backbone）

- **一个 `θ`，四个头**：`π`（动作块）、`W`（潜空间转移）、`V`（达成/存活概率）、`Λ`（撤回风险率）。共享视觉-语言 trunk；技能差异由门控/LoRA 承担，**部署时只有一个 checkpoint**。
- **训练数据**：32 个公开数据集（模仿学习） + UIP-12′ 的"撤回-恢复"合成数据（`V/Λ` 监督） + UIP-11′ GSO 的"计划-得分"对（`V` 校准）。
- **合规性**：推理期不调用任何外部 VLM/API；RAPS 的检索库是离线公开数据，不是第二个模型；GSO/DRF 只离线使用。
- **风险**：`W` 的误差会在前瞻中累积 ⇒ 限深（2–3 个 option）、用真实观测做一致性校验、`V` 做保守下界。

## 3. UIP-17 · LRHP（潜空间滚动规划）+ UIP-21 · APD（摊销蒸馏）

- **前瞻**：在 `z` 上用 `W_θ` 展开候选 option（含承诺强度），用 `V_θ, Λ_θ` 估终局分，用分支定界 + 乐观上界（"所有未达成权重之和"）做 anytime 搜索。**只承诺首个 option**，执行完再观测、再规划（receding horizon）。
- **搜索空间压缩**：候选选项由 UIP-14′ 技能图给出；每层只留 top-b 个（按 `V` 上界 + 风险下界），次数由 UIP-18 的预算决定。
- **UIP-21 APD（摊销）**：用规划器离线产生的"状态→计划"对，把 **planner 的行为蒸馏回 `π` 头**（expert iteration / DAgger 风格）。测试时可以"零搜索"直接用 `π`，只有在账本报警或时间富余时才开浅层 LRHP。这把"想清楚"的收益从**每次都付**变成**按需付**，直接服务实时性。
- **风险**：蒸馏会把规划器的错误一并固化 ⇒ 保留一个"浅搜索 + 价值校验"的旁路，并监控二者分歧。

## 4. UIP-18 · VOC（Value-of-Information Compute Allocation）

把核验、重规划、承诺统一成**每秒钟买到的期望分数**：

```
核验 g 的边际价值   ≈ w_g · σ_g · P(已撤回未观测) · P(还来得及重做)
承诺 g 的边际价值   ≈ w_g · (T − τ_g) · (λ_g − λ'_g)
规划/搜索的边际价值 ≈ 当前计划与最优上界的 gap 缩减率
每项都除以它的延迟成本 c，按性价比贪心填预算 B(t)
```

- **动态预算**：远离截止期时多花在"承诺/搜索"，临近截止期时预算转向"高 `wλ` 的末段核验与重做"。
- **对应接口**：`obs_delta_indices` 少堆叠帧、`image_resize` 降分辨率以换取更短延迟——这些"省下来的延迟"就是 VOC 的预算来源。
- **风险**：VOI 估计依赖 `σ_g, λ_g` 的校准；用 UIP-15′ 做保守裁剪（估计过高就按上限封顶）。

## 5. UIP-19 · RAPS（Retrieval-Augmented Plan Skeleton）

- **机制**：维护一个离线"计划骨架库"——对 32 个公开数据集的每条 episode，抽取 `(语言, 首帧表征, 子目标序列, 关键原语参数)`。在线时用 `E_θ` 的共享表征检索 top-1/top-k，作为规划器的**初始顺序/参数先验**或"未见物品"的兜底计划。
- **为什么有用**：`unseen_object_*` 与背景变化会让 `π` 漂移，但**"先归位再插入"之类的计划骨架**通常不变；检索提供一个不增加新模型的强先验，且天然合规（只是数据，不是模型）。
- **风险**：检索到"形似神不似"的骨架会误导 ⇒ 用 `V` 头做前置可行性检查 + 软融合（骨架只作排序先验，最终仍由规划器裁剪）。

## 6. UIP-20 · AUAP + IAC（对抗撤回 + 不可逆承诺）—— 本轮第二旗舰

- **AUAP（对手模型）**：把 `human_*` 的撤回写成对手策略 `u* = argmax_{g,t} w_g · P(撤回可成功) · P(来不及重做)`；训练时用 UIP-12′ 联合采样"撤回哪个子目标、在什么时刻撤回"，按对抗/风险敏感（CVaR）目标优化，而不是均匀注入。
- **IAC（承诺选择）**：对每个 option 评估承诺档位 `κ ∈ {0, 0.5, 1}`：
  - 成本：`dt(κ) = dt + c·κ`（如插得更深、压得更紧、多转半圈）；
  - 收益：`λ(κ) = λ·(1−κ) + λ_irrev·κ`；
  - 决策：在剩余 Slack 内选 `argmax_κ w·(1 − e^{−λ(κ)(T−τ)}) − γ·dt(κ)`。
- **核心洞见（合成实验支持）**：**承诺是比"重排顺序"大得多的杠杆；但"全承诺"在紧截止期会超时归零**，因此必须按剩余时间做**背包式分配**——这正是 UIP-18 与 UIP-01‴ 的存在理由。
- **风险**：过度承诺可能损害后续步骤的可操作性（例如压太紧导致无法再调整）⇒ 把"承诺"限制在**语义上本就不可逆**的步骤（插到底、倒出、叠放到位），并在仿真里先验证可撤销性。

## 7. 升级项（相对 v2）

- **UIP-02″ VSL**：计分账本从"步骤清单"升级为 `(w_i, A_i, τ_i, λ̂_i, κ_i)`，直接支撑终局加权存活。
- **UIP-09″ UHE**：从"二值检测撤回"升级为"估计风险率 `λ_i`"（可用生存分析/泊松回归从 DRF 与真机日志标定）。
- **UIP-11′ GSO**：从"给单条 rollout 打分"升级为"给**计划**打步骤分"，用于校准 `V/Λ` 与评估规划质量；仍然只作**结构/顺序裁判**，不作像素级成败裁判。
- **UIP-12′ DRF**：从"复现撤回动作"升级为"联合采样撤回目标 × 时机 × 速度"，并记录 `(τ, λ)` 标签，喂给 UIP-09″/UIP-16。
- **UIP-13″ BAS**：块长、核验频率、规划深度统一由 UIP-18 的预算分配；不再按"阶段"手工拍。
- **UIP-14′ MSGR**：技能图节点变成 **option**（带 pre/post/Δ），使规划器可直接在图上搜索。
- **UIP-15′ CSG**：护栏扩展到"规划延迟 + 重做次数 + 承诺总量"，直接对应 README 的可信度口径。

```python
class PARHV:  # UIP-01‴ = TEB + LRHP + VOC + IAC
    def __init__(self, net, graph, weights, T, latency_B):
        self.net, self.graph, self.T, self.latency_B = net, graph, T, latency_B
        self.weights = weights

    def reset(self):
        self.ledger = Ledger(self.weights)   # A_i, tau_i, lambda_i, kappa_i
        self.t = 0.0

    def get_action(self, obs):
        z = self.net.encode(obs)                          # one trunk pass
        self.ledger.update(self.net.value(z, self.ledger))
        budget = self.voc.budget(z, self.ledger, self.t, self.T)
        plan = self.lrhp.plan(z, self.ledger, self.graph, self.T, budget)
        opt, kappa = self.iac.select(plan[0], self.ledger, slack=self.T - self.t)
        chunk = self.net.act(z, opt, kappa)               # length <= K_MAX
        self.t += len(chunk) * self.dt_ctrl
        return chunk
```

```python
def plan(self, z, ledger, graph, T, budget):
    root = Node(z=z, ledger=ledger, t=self.t)
    frontier = MaxHeap([root], key=upper_bound)           # optimistic
    best = root
    t0 = clock()
    while frontier and clock() - t0 < budget:
        n = frontier.pop()
        if n.is_complete():
            best = max(best, n, key=J)
            continue
        for opt in graph.options(n.next_goal):
            for kappa in (0.0, 0.5, 1.0):                 # IAC knobs
                c = n.expand(opt, kappa, W=self.net.world)
                c.ub = c.score + remaining_weight(c) - risk_lower_bound(c)
                frontier.push(c, key=c.ub)
    return best.path or self.net.amortized_plan(z, ledger)  # APD fallback
```

```python
def select(self, opt, ledger, slack):
    best, best_j = (opt, 0.0), -1e9
    for kappa in (0.0, 0.5, 1.0):
        dt = opt.dt + opt.commit_cost * kappa
        if dt > slack:
            continue                                   # hard deadline
        lam = opt.lam * (1 - kappa) + opt.lam_irrev * kappa
        j = opt.weight * (1 - exp(-lam * (self.T - (self.t + dt)))) - self.gamma * dt
        if j > best_j:
            best, best_j = (opt, kappa), j
    return best                                        # degrade to fastest if empty
```

```python
def score_plan(task, sim, plan):   # UIP-11' GSO: plan-level oracle (illustrative)
    total = 0
    for opt in plan:
        sim.execute(opt)
        total = max(total, rule_score(task, sim))      # geometric predicates per step
    return total
```

## 9. 合成实验（可复现，非真机）

- **脚本/结果**：`tmp/v3_plan_sim.py` → `tmp/v3_plan_sim.json`（3 子目标；30k episodes/臂；承诺 = 风险率 ×0.1、每个 +3 s；重做 6 s 或 20 s）。这是**决策论 sanity check**，只用于给"杠杆"排序，不用于宣称真机增益。

| 场景 | 固定·不承诺 | 后置高暴露·不承诺 | 只承诺最高 `wλ` | 全承诺 |
|---|---|---|---|---|
| R1 T=40 / 重做 6s | 93.03 / 81.4% | 93.03 / 81.4% | 96.74 / 89.9% | **99.28 / 98.0%** |
| R2 T=30 / 重做 6s | 92.65 / 80.5% | 92.78 / 80.9% | **97.08 / 90.7%** | **0.00 / 0.0%（超时）** |
| R3 T=50 / 重做 20s | 79.79 / 52.0% | 79.72 / 52.1% | 90.18 / 71.5% | **97.70 / 93.6%** |

- **结论**：① 重排顺序单独 ≤0.6 分（噪声级）；② 承诺在慢重做档把平均分 +17.9、成功率 +41.6pt；③ 紧截止期下"全承诺"归零，**承诺必须按 Slack 分配**。这直接决定了资源应投在 UIP-20/IAC + UIP-18/VOC，而不是"最优步骤排序"。
- **局限**：泊松风险、确定性耗时、无感知误差；真实 `λ` 需 UIP-09″/UIP-12′ 标定，承诺语义需真机确认。

## 11. 合规、风险与资源

- **单模型**：一个 checkpoint、一条 trunk；`W/V/Λ` 只是头；RAPS 是离线数据检索；GSO/DRF 只离线。若手册明确禁止外部大模型，本方案在推理期**零外部调用**。
- **仿真自欺**：`W` 是学出来的，前瞻会放大误差 ⇒ 限深、用观测校验、GSO 只作结构裁判、保留真机锚点（E208）。
- **截止期灾难**：承诺/搜索都吃时间 ⇒ 硬 Slack 约束 + UIP-15′ 护栏 + APD 零搜索兜底。
- **口径未定**：若"达成即锁定"，核验-重做收益下降；但"不可逆完成"在两个口径下都不亏，故 IAC 是稳健下注。
- **时间线**：第 1–2 周 TEB 骨架（选 T26 插网线 / T27 叠碗 / T19 拉链做三头原型）；第 3–4 周 LRHP + VOC + IAC（GSO 与合成校准）；第 5–6 周 RAPS + DRF 对抗采样 + APD；第 7–8 周 多端口压测与 CSG；第 9 周起真机锚点。

## 12. 本轮最大风险 & 押注

**一句话**：若真实计分是"达成即锁定"、或人为撤回远少于规则文本，那么 v3 的前瞻规划与承诺就是**为不存在的对手支付延迟税**，会同时伤成功率与可信度；必须先用手册/真机钉死"撤回是否扣分"，再放大自动化。

**→ 押注：UIP-20（IAC 不可逆承诺）× UIP-18（VOC 承诺分配），由 UIP-01‴（PARH-V）在潜空间里调度**——合成实验显示它是比"最优顺序"大一个数量级的杠杆，且完全落在选手 API 与离线算力之内；先用 UIP-11′ 判分与 UIP-12′ 造数据校准，再用真机锚点确认口径。
