动研究循环·新灵感三元组第 1 轮；本轮灵感：「排行榜」×「预训练」×「ROS2」

> **基线**：承接 MetricVoiceGauge-NCD-HUTDH-v22 层次化能量证书体系 HPC-E / CFC++ / HDL / ACSC / DCSC。
> 本轮纪律：**排行榜是可审计的模型选择契约、预训练是带先验的证据生成器、ROS2 是可验证的部署与通信骨架**。不推倒 v22：Fil_hierarchical / K_energy / CertBox / conformal 校准全部保留。本轮只做一件事：在 v22 的联邦证书之上加一层「排行榜驱动的预训练模型编排与 ROS2 可审计部署」层，把模型选择从离线经验升级为在线可证排名，并封堵 v22 最大风险（分层边界模糊导致振荡）。

## 0. 直觉与动机

**灵感 1（排行榜 → 模型选择的契约化与淘汰）**
直觉：v22 有多个感知/能量模型并存，却缺乏统一的、带失效上界的可比较排序。排行榜把 (覆盖率、定位误差界、能耗、延迟) 编译为单调标量 L_i，并以 Merkle 根版本化。核心创新：**安全排行榜 L_safe** 与 **活性排行榜 L_live** 双轨制，安全轨优先且不可协商。关键反直觉点：排行榜不是“分数越高越好”，而是“在安全约束下最大化活性的帕累托前沿”，低分模型自动进入影子模式，不参与 CFC++ 计数。

**灵感 2（预训练 → 先验迁移与 conformal 安全化）**
直觉：从零训练代价高且样本难标。预训练骨干提供类条件几何先验与深度特征 φ(x)。核心创新：**预训练证书适配器 PCA2**：冻结骨干 + 轻量头部 + 在线 conformal 校准，产出以 ≥1-α 概率成立的 CertBox_pre。预训练的分布漂移 via 排行榜触发重校准，而非重训。关键反直觉点：预训练的“通用性”通过 conformal 转化为“可证的特异性”，假阳性被显式上界控制。

**灵感 3（ROS2 → DDS QoS 的可审计通信与组件生命周期）**
直觉：v22 的证书在进程内有效，跨节点传播依赖手工拷贝。ROS2 的 DDS QoS、组件生命周期、参数事件提供原生审计点。核心创新：**ROS2 安全编排器 RSO**：证书以 ROS2 专用消息 CertMsg 随 QoS RELIABLE + DEADLINE 传输，节点启动/停止/参数变更写入审计日志。控制路径仅 O(1) 查询证书缓存，事件路径 10Hz 注入。关键反直觉点：ROS2 的“实时性”被用于“审计延迟的上限保障”，而非仅降低延迟。

**三者如何统一**
统一为 **排行榜驱动的预训练模型在 ROS2 上的可审计编排**：LMR 决定“用哪个预训练骨干”，PCA2 决定“它能否产出可证 CertBox”，RSO 决定“证书如何安全地在 ROS2 图中传播与失效”。共享状态 ζ_rank = ζ_pgev ∪ (Leaderboard_t, ModelSel_t, R2QoS_t)。准入门：**HPC-E-R = HPC-E ∧ RankCert ∧ R2Delivery**——几何∧能量∧排行榜合格∧ROS2 交付可审计，才进入执行。

## 1. 研究问题

- **Q1（排行榜的可证单调性）**：如何设计 L_safe = f(覆盖, δ_loc, 能耗, 延迟) 使得排名提升不破坏 Exec ⊆ Exec_v22？排行榜更新频率与 conformal 窗口如何对齐以避免排名振荡？
- **Q2（预训练的先验安全化）**：预训练骨干的类条件先验何时可安全收紧 CertBox？分布漂移检测阈值如何与排行榜降级联动？冻结骨干下 conformal 覆盖能否在 O(1) 开销内维持？
- **Q3（ROS2 的可审计交付）**：DDS QoS 参数如何映射到证书新鲜度 TTL？节点失效/网络分区时，RSO 如何保证 fail-safe 退化到保守证书而非静默丢弃？审计日志的 Merkle 链如何与规则库版本绑定？

## 2. 设计原则

**P43 排行榜单调律**
模型选择集合 Monotone：若 m_i 在 t 时被选中，则在 t+1 时仅当 L_safe(m_i) 仍 ≥ θ_safe 且 L_live 中无更优替代时保留。淘汰不增加可达集，`Exec_Rank ⊆ Exec_v22`。

**P44 预训练安全化律**
预训练输出必须经 PCA2 的 conformal 校准后才进入 Obs_t。先验收紧仅在 CTS 尺度不变子集上进行，且校准失败即回退到 v22 DCSC。`CertBox_pre ⊆ CertBox_v22` 在失效时成立。

**P45 ROS2 可审计交付律**
证书传输必须满足 QoS 契约：RELIABLE + DEADLINE ≤ τ_cert。若违反，接收方自动失效证书并上报。节点生命周期事件必须写入审计日志，日志哈希纳入规则库 Merkle 根。

## 3. 与基线的接口

- LMR 失效 → 回退到 v22 DCSC 的固定模型集合；
- PCA2 校准失效 → 预训练模型进入影子模式，不计入 CFC++；
- RSO 通信失效 → 本地保守模式，`Exec_Rank ⊆ Exec_v22` 保持；
- 三者全失效 → 完全回退 v22。

## 4. 预期贡献

1. 首次把模型排行榜形式化为可审计安全契约，并与 conformal 证书耦合；
2. 预训练骨干通过 PCA2 获得可证的 CertBox，迁移成本降为 O(1) 校准；
3. ROS2 DDS QoS 被编译为证书新鲜度与失效审计，跨节点安全继承可验证；
4. 排行榜 + 预训练 + ROS2 的三层编排封堵 v22 振荡风险。

## 5. 本轮最大风险
**一句话**：排行榜的在线更新若与 conformal 校准窗口不同步，可能产生“排名已升但覆盖已失效”的时序错位，导致预训练模型以过期置信被选中而合规地输出假安全证书。

## 2. 算法设计

### 2.1 形式化定义

**定义 926 预训练证书适配**
PCA2(m, x) = (ŝ, ε̂, φ) 满足 P(err ≤ ε̂ | ŝ) ≥ 1-α 且 φ = f_backbone(x)。

**定义 927 排行榜合格谓词**
RankCert(m_i,t) ≜ L_safe(m_i,t) ≥ θ_safe ∧ PCA2覆盖有效 ∧ R2Delivery(m_i) = OK。

**定义 928 ROS2 可审计交付**
R2Delivery(m_i) ≜ ∃ 消息 CertMsg 在 [t-TTL, t] 内以 QoS RELIABLE 送达且审计日志哈希一致。

### 2.2 算法步骤

```python
# IP-436 LMR
class LeaderboardModelRanker:
    def update(self, eval_batch):
        for m in self.models:
            cov, delta, e, lat = self.evaluate(m, eval_batch)
            m.L_safe = w1*cov + w2*(1-delta) - w3*e - w4*lat
            m.L_live = self.compute_live(m)
        # Merkle 根
        self.root = merkle([m.L_safe for m in self.models])
        return self.top_k(k=3, filter=lambda m: m.L_safe>=θ_safe)

# IP-437 PCA2
class PreTrainedConformalAdapter:
    def certify(self, x):
        feats = self.backbone(x)  # 冻结
        head_out = self.head(feats)
        s = softmax(head_out).max()
        eps = self.calibrator.quantile(s, alpha)
        return CertBox(inflate(head_out.box, eps), score=s, phi=feats)

# IP-438 RSO
class ROS2SafetyOrchestrator:
    def deploy(self, model_sel):
        for m in model_sel:
            node = rclpy.create_node(f"cert_node_{m.id}")
            pub = node.create_publisher(CertMsg, f"/cert/{m.id}", 
                                        QoSProfile(reliability=RELIABLE, deadline=Duration(seconds=0.2)))
            node.set_on_lifecycle_callback(self.audit_log)
        self.audit_merkle = update_merkle(self.log)

# IP-439 RCF
def ranked_fusion(votes, leaderboard):
    valid = [v for v in votes if RankCert(v.model, leaderboard)]
    if len(valid) < N-F: return "CI"
    # 加权多数
    return weighted_majority(valid, weights=[v.L_safe for v in valid])
```

主循环：
1. 每 10Hz：LMR 更新排行榜，生成 ModelSel_t；
2. 每 50Hz：PCA2 生成 CertBox_pre，写入本地缓存；
3. RSO 以 DDS QoS 发布 CertMsg，接收方校验 TTL 与 Merkle；
4. RCF 仅对 RankCert 成立的票参与 CFC++；
5. HPC-E-R 准入门检查：HPC-E ∧ RankCert ∧ R2Delivery。

### 2.3 复杂度分析

- LMR 更新：O(K log K) 排序，K 为模型数，通常 K ≤ 10；
- PCA2 推理：O(C_backbone + C_head)，骨干冻结，推理延迟 ≈ 12ms；
- ROS2 传输：O(1) 每节点，DDS 心跳 O(N)；
- 总控制路径开销：O(1) 查询证书缓存，事件路径 10Hz。

### 2.4 正确性论证

**引理 1 单调性**：RankCert 为真 ⇒ CertBox_pre ⊆ 安全膨胀。由 conformal 保证 P(err≤ε̂)≥1-α。
**引理 2 安全继承**：若 RankCert 失效，模型进入影子模式，不计入 CFC++，故 Exec_R ⊆ Exec_v22。
**定理 1**：在 LMR 单调、PCA2 conformal 有效、R2Delivery QoS 满足的前提下，Exec_R ⊆ Exec_v22 且证书可审计。
证明：HPC-E-R 要求三条件交集，任一失效退回 v22 保守模式，交集单调递减。

### 2.5 已知风险

排行榜更新与 conformal 窗口时序错位会导致过期置信被选中；ROS2 网络分区时 DDS 心跳丢失可能导致证书静默失效，需 fail-safe 到保守模式；预训练先验失配时 PCA2 回退可能引发活性坍缩。
