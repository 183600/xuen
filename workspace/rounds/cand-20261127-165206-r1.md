## 1. 直觉与动机（两个灵感的碰撞）

**灵感 1（力矩传感 → 赛题没有力矩通道，但「指令-实际」残差就是一个免费的力矩传感器）**
直觉：所有人看到 F21 的观测目录都会说「没有力/触觉，接触任务只能靠视觉」。但策略自己知道刚命令了什么：上一块动作是策略输出的目标关节位置，观测里又有实际关节位置。在位置控制机器人上，外力不会凭空消失，它会表现为「命令到了、实际没到」的跟踪残差；残差越大、持续越久，越可能是接触/碰撞/夹滑。这正是经典的无传感器力矩估计（disturbance observer）：`τ_ext ≈ K_p(q_cmd − q_obs) + D_p(q̇_cmd − q̇_obs) − τ_dyn`。核心反直觉点：**我们不需要力矩传感器，我们需要的是「自己刚命令了什么」与「机器人实际做了什么」之间的差；这个差在接口里免费存在，而且被所有只盯 RGB 的队伍忽略了。**

**灵感 2（多机协同 → 赛题里的「多机」不是两台机器人一起搬东西，而是同一份策略在 N 台机器人上不打架）**
直觉：F22 明确评测跨 N 台机器人、随机顺序、每端口独立。这不是多机器人任务协作，而是**多本体一致性**：同一份权重、同一套阈值，要在关节零位、摩擦、相机外参、桌面高度都不同的 N 台本体上都成立。真正的「协同」对象是标定，不是任务。更关键的是，F21 的虚拟力矩信号对每台机器人的 `K_p`、摩擦、零位极其敏感——在 A 机器人上调好的接触阈值，到 B 机器人上可能全是假阳性。核心反直觉点：**多机协同在赛题里是一个「跨本体校准」问题；谁先把每台机器人的力标定 token 在 reset 期估出来，谁的接触策略才不会在多机上碎掉。**

**碰撞与统一**：力矩传感给出「接触可观测性」，多机协同给出「接触可观测性的本体依赖性」。两者相乘，得到本轮的核心机制：**reset 期每机器人一次力校准 + episode 内虚拟力矩接触观测 + 块边界的力条件恢复**。它同时打两个痛点：P4（无触觉）与隐藏的跨本体轴（F22）；而且完全在单模型/单 PolicyService 边界内——观测器与恢复状态机是同一个策略服务的内部组件，不是外挂模型（F28）。

**与第 2 轮的关系**：第 2 轮说「中期胜负手在数据引擎」；本轮不推翻，而是给数据引擎加一个**力的监督信号**：虚拟力矩残差可以作为 32k 示教的免费弱标签，自动切出「接触段/滑移段/碰撞段」，让 I5 的合成恢复示教有的放矢；同时给 I2 的跨本体数据加权提供依据。**力不是新模态，而是已有数据的一个新切面。**

## 2. 严谨定义（先直觉，后定义）

### 2.1 虚拟力矩观测器（VTO）
- 记策略在时刻 `t` 的上一块指令为 `q_cmd(t)`（由我们自己缓存，精确已知），观测关节位置为 `q_obs(t)`，速度由历史差分 `q̇_obs(t) ≈ (q_obs(t) − q_obs(t−Δ))/Δ`。
- 位置控制器准静态近似：
  `τ_ext(t) ≈ K_p (q_cmd(t) − q_obs(t)) + D_p (q̇_cmd(t) − q̇_obs(t)) − τ_g(q_obs) − τ_f(q̇_obs)`。
- 定义虚拟力矩 `τ̂(t) = K̂_p r(t) + D̂_p Δr(t) − τ̂_dyn(t)`，其中 `r = q_cmd − q_obs`，`K̂_p, D̂_p, τ̂_dyn` 由本体标定 + 学习残差给出。
- 接触状态 `c(t) = 1[ ||τ̂(t)||_Σ > θ_c ]`；滑移 `s(t) = 1[ ||τ̂(t)|| 突降 + 夹爪开度变化 + 物体视觉位移 ]`。
- **可观测性条件**：`SNR = ||K_p r|| / σ_noise > 1` 且接触持续时间 `> 1/f_ctrl`。若 `SNR<1`，虚拟力矩不可观测，必须退回视觉/关键点（I3）或主动激励。
- **关键设计**：VTO 不是新输入通道，而是对已有观测的**因果重解释**；它不改变接口，只改变我们如何使用历史。

### 2.2 跨本体力校准（CEFC）
- 每台机器人有一个本体参数 `θ_i = (q_offset, K_p scale, friction, camera extrinsics, table height)`。
- `reset()` 无观测，故校准发生在首个 `get_action`：用首帧静态位姿 + 已知重力项估计 `q_offset` 与 `τ_g`；用前 1–2 个块的执行残差估计 `K_p` 的尺度因子 `α_i`（`K_p,i = α_i K_p,0`）。
- 力阈值归一化：`θ_c,i = θ_c,0 / α_i`；这样 A 机器人上的接触判据在 B 机器人上仍然成立。
- 训练期跨本体随机化：`q_offset ± 2°`、`K_p ± 20%`、摩擦 ±30%、相机外参 ±5°、焦距 ±5%、桌面高度 ±2cm、夹爪间隙 ±1mm；用 DiverseManip 的跨场次差异做真实多样性补充。
- **可辨识性条件**：首帧必须提供足够的重力激励（不同关节角）且至少有一个自由空间运动段；若首帧是奇异位形或全程接触，则退化为保守阈值 + 视觉融合。
- **合规边界**：CEFC 是 episode 内的状态估计/系统辨识，不是权重更新；默认不跨 episode 缓存（`reset()` 清空），也不跨端口共享（F22）。

### 2.3 力条件恢复（FCR）
- 在块边界 `t_k`，VTO 给出 `(c, s, τ̂)`；策略从模式集 `M = {continue, slow, re_approach, re_grasp, retreat}` 中选一个，作为下一个块的生成条件（soft prompt / mode token），而不是替换 VLA 的输出。
- 恢复动作来自 I5 的合成接触失败示教，不在推理期手工写新动作分布。
- **安全约束**：恢复触发必须满足滞回（连续 2 个块）且离线估计 `P(成功|恢复) − P(成功|继续) > margin`；否则默认 `continue`——力观测器不能伤原本会成功的 episode。

## 3. 对第 2 轮痛点的增量修订

- **P4（无触觉）**：从「无法缓解」升级为「可间接观测」：VTO 把跟踪残差变成接触/滑移信号；但仍受可观测性条件约束，不是万能触觉。
- **P2（泛化缺口）**：新增隐藏轴——跨本体（F22）是 32 任务 × 全部 episode 的乘性轴；力阈值不校准会把它放大。
- **P3（人为干扰）**：新增第二条检测路径：人手推搡/遮挡时，VTO 可在手出视野时通过力矩突变检测接触；与视觉手部检测互补。
- **P5（时间压力）**：块内开环（F23）使力反馈延迟 = `T_a/f`；为力反馈牺牲 chunk 长度会提高推理频率，需与 p99 预算联合优化。
- **P8（示教质量）**：新增免费弱标签：VTO 残差可自动切分接触段/滑移段，给 I5 合成示教和 I2 质量加权提供帧级标签。
- **新增 P9（力可观测性）**：残差 SNR 可能低于噪声底，尤其轻接触/软物体；VTO 不是万能的，必须有视觉回退。
- **新增 P10（跨本体可辨识性）**：reset 无观测、首帧可能奇异；单 episode 内的 `K_p/零位/摩擦` 可能不可辨识，需要保守先验 + 训练期随机化。

## 4. 研究问题（本轮立项 Q9–Q11，Q1–Q8 保留）

- **Q9（虚拟力矩的可观测边界）**：在 15Hz、位置控制、无速度/力矩通道的接口下，跟踪残差对哪些接触事件（硬接触、软接触、夹滑、插入、碰撞）有足够 SNR？需要多长的历史栈与多小的 `T_a`？
- **Q10（跨本体力校准的可辨识性）**：reset 期一次（或前 1–2 块）能否估计出足够的本体参数，使接触阈值在 N 台机器人上不变？哪些参数必须训练期随机化、哪些可以 episode 内估计？
- **Q11（力条件恢复的净收益）**：在块内开环约束下，VTO 触发的恢复/减速/重抓，能否在接触密集任务上提升成功率与步骤分，而不伤原本成功的 episode？恢复策略的触发滞回与「不伤害」判据如何定？

## 5. 设计原则（新增 PR6/PR7，其余保留）

- **PR6 可观测性律**：任何「感知→决策」模块，必须先证明其信号在接口中的 `SNR>1` 且延迟 < 被控事件的持续时间；否则只能用于训练期标注/数据生成，不能进推理期。与 PR4（部署门禁）、PR5（数据杠杆）互补。
- **PR7 单模型内聚律**：所有新增能力必须能装进同一个 PolicyService / 同一套权重；若需要第二个模型，优先改为同一模型的辅助头/辅助任务；不能为不同任务切换模型（F28）。
- PR1–PR5 保留（第 1–2 轮）。

## 7. 本轮最大风险

**一句话**：本轮方案的最大风险是**力信号的可观测性**——在 15Hz、位置控制、无速度/力矩通道、且动作块开环执行的接口下，跟踪残差可能被控制器刚度、重力/摩擦、编码器噪声淹没，轻接触与软物体尤其可能 `SNR<1`；若 VTO 在真机上不能稳定区分「接触」与「自由空间加减速」，那么 I11 的跨本体校准和 I12 的力条件恢复都会变成「用噪声触发恢复」，反而伤及原本会成功的 episode——所以第一件事不是训模型，而是用 32k 示教 + 仿真力标签先证明 VTO 的 AUROC 与延迟达标。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I10 虚拟力矩接触观测器（VTO） ★★★★★

- **动机**：F21 的观测目录没有关节速度、力矩、电流、触觉；F26 的 32 任务里大量是接触密集操作；F20 榜首只有 29.7% 成功率，剩余 70.3% 的失败里，接触/抓取/插入失败是最大的一类。纯视觉策略只能看到「有没有碰到」的外观，看不到「碰得对不对、有没有打滑、插进去多深」。
- **核心思想**：策略自己发出的上一块动作是精确已知的目标关节位置 `q_cmd`，观测里有实际关节位置 `q_obs`。在位置控制机器人上，外部接触力矩会表现为跟踪残差 `r = q_cmd − q_obs`。用 `τ̂ = K̂_p r + D̂_p Δr − τ̂_dyn` 估计虚拟力矩，再用一个小辅助头把 `τ̂` 映射为接触概率、滑移概率、接触方向。**不新增输入通道，不改变接口，不新增独立模型。**
- **与现有方案差异**：
  - 纯 VLA 队伍：只用 RGB + 本体位置，接触信息被当作噪声；
  - 外挂力传感器队伍：接口没有力矩通道，硬件上加传感器也无法传给策略；
  - 手工阻抗/力控队伍：引入新的动作分布，且可能违反单模型红线（F28）。
  - VTO 是把已有信号做**因果重解释**：它不改变策略输出什么，只改变策略如何理解「自己刚做了什么、机器人实际做了什么」。
- **技术可行性**：中-高。
  - 指令缓存：自己发的 chunk 精确已知；与观测用 ±1 步对齐搜索吸收 evaluator 抖动。
  - 历史栈：`obs_delta_indices` 给左右臂 `[-8,-6,-4,-2,0]`（或 `[-4,-2,0]`），ee pose/夹爪同理；带宽增加可忽略。
  - 动力学补偿：优先用 G1 URDF 的刚体动力学 `τ_dyn = M(q)q̈ + C(q,q̇)q̇ + g(q) + f(q̇)`；拿不到 URDF 时用每关节线性黑箱 + 高通残差抑制慢漂移。
  - 接触头：8 帧 × 14 关节残差 + 夹爪 + ee 速度 + 视觉接近度，输入约 120 维；0.1M 参数 MLP/1D-CNN；作为 VLA 辅助头或同服务内小头。
  - 标签：Isaac Lab 仿真带力传感器给强标签；真实数据用夹爪开合事件、任务成功、接触密集段给弱标签；弱标签用 positive-unlabeled 学习。
- **所需资源**：1×24GB GPU 训练接触头 1–2 GPU 日；32k 示教重放 1 人周；无需新数据下载。
- **落地步骤**：① 缓存指令 + 对齐观测，重放 32k 示教算残差；② 用夹爪/任务阶段做弱标签，先看残差在接触段是否显著抬升（最简单的 sanity check）；③ Isaac Lab 采力标签，训练接触头；④ 在 3 个接触密集任务上做 L0 AUROC/延迟；⑤ 接 I12 做块边界恢复；⑥ 单任务通道 A/B。
- **风险**：
  - 轻接触/软物体 `SNR<1` → 视觉/关键点融合 + 主动激励（仅在安全预接触段）；
  - 低层控制器不是纯 PD（可能是阻抗/导纳）→ 学习残差映射，用相对变化而非绝对力；
  - 指令-观测时间错位 → 指令缓存 + 对齐搜索 + 鲁棒窗口特征；
  - 自由空间快速运动假阳性 → 夹爪状态/视觉接近度门控 + 滞回。

### I11 跨本体力校准与归一化（CEFC） ★★★★

- **动机**：F22 评测跨 N 台机器人、随机顺序、每端口独立。同一份权重、同一套接触阈值，要在关节零位、`K_p`、摩擦、相机外参、桌面高度都不同的 N 台本体上成立。VTO 的残差-力映射对 `K_p` 和零位极其敏感：在 A 上 `θ_c=1.0`，到 B 上可能等效成 `0.6` 或 `1.5`，接触检测直接碎掉。
- **核心思想**：把「多机协同」重新定义为「多本体一致性」——不是多机器人协作任务，而是同一策略在 N 台本体上的**力标定一致性**。在 `reset()` 后的首个 `get_action`（以及前 1–2 个块）估计一个 per-port 的标定 token：关节零位、`K_p` 尺度 `α_i`、桌面高度、相机归一化；用 `θ_c,i = θ_c,0/α_i` 归一化力阈值；训练期做跨本体随机化，让 VLA 见过这些差异。
- **与现有方案差异**：
  - 单本体训练队伍：把 N 台当一台，跨本体轴全丢；
  - 手工调参队伍：N 未知、端口随机分配，无法逐台手调；
  - CEFC 是 episode 内系统辨识，不是在线学习；默认不跨 episode 缓存、不跨端口共享（F22），合规风险低。
- **技术可行性**：中-高。
  - 首帧：估计 `q_offset`（对已知 home 位形或重力模型）、桌面高度（平面检测/首次接触）、相机归一化（消失点/物体尺度）。
  - 前 1–2 块：在自由空间段用已知重力项反解 `K_p` 尺度 `α_i`；若首块全程接触/奇异，退化为保守先验。
  - 训练期随机化：`q_offset ±2°`、`K_p ±20%`、摩擦 ±30%、相机外参 ±5°、焦距 ±5%、桌面高度 ±2cm、夹爪间隙 ±1mm；DiverseManip 提供真实跨场次差异。
  - 归一化：给 VLA 的关节角减去估计零位，ee pose 转到桌面坐标系；力阈值除以 `α_i`。
- **所需资源**：标定估计器 1 人周；训练随机化改动 2–3 天；1×GPU 做 L0 仿真验证。
- **落地步骤**：① 标定 token schema；② 首帧/首块估计器；③ 训练期随机化；④ L0 跨本体扰动测试（接触 AUROC 退化斜率）；⑤ 真机双机器人抽测（若可申请）；⑥ 接 I10/I12。
- **风险**：
  - 单 episode 参数不可辨识 → 只自适应最敏感的阈值尺度，其余用保守先验 + 训练期随机化；
  - 校准动作伤任务 → 默认被动估计（利用自然首段运动），不做专用激励；
  - 跨 episode 缓存可能违反 `reset` 语义 → 默认不缓存；如需缓存仅限运动学零位，并向组委会书面确认。

### I12 力条件恢复（FCR） ★★★★

- **动机**：VTO 在块边界给出接触/滑移状态；I5 能合成「偏离→修正」示教；但缺一个「什么时候恢复、恢复成什么模式」的决策器。接触密集任务的失败往往不是「不会做」，而是「做偏了之后继续硬做」。
- **核心思想**：在块边界 `t_k`，用 VTO 状态从 `{continue, slow, re_approach, re_grasp, retreat}` 中选一个模式，作为下一个块的**生成条件**（mode token / soft prompt），而不是替换 VLA 的输出。恢复动作来自 I5 的合成接触失败示教，保证动作在数据分布内；触发用滞回 + 离线净收益门禁，保证不伤原本会成功的 episode。
- **与现有方案差异**：
  - I3 关键点视觉伺服：几何、只覆盖接触段、需要关键点检测；
  - 手工恢复原语：引入新动作分布，且难以覆盖多任务；
  - FCR 用「力状态触发 + 数据内恢复 + 单模型 mode token」，是 I3/I5 之间的缺失决策层。
- **技术可行性**：中。
  - 模式集小（5 个），每个模式对应一个可学习的条件 embedding；
  - 恢复示教由 I5 生成：打滑（夹爪闭合但物体滑）、插偏（接触方向偏）、碰撞（残差尖峰）、夹空（夹爪闭合无接触）；
  - 触发：连续 2 个块满足条件 + `P(成功|恢复) − P(成功|继续) > margin`（离线估计）；
  - 安全：动作 clamp + 块边界平滑，满足 F24 的动作良构/时延平滑。
- **所需资源**：模式 token 训练 1×24GB GPU 2–3 日；I5 合成管线复用；1 人周工程。
- **落地步骤**：① 定义 5 模式与触发条件；② 用 I5 生成接触失败示教；③ 训练 mode token；④ L0 净收益/假触发率；⑤ 单任务通道 A/B；⑥ 与 I4 人手干扰合并评估。
- **风险**：
  - 恢复动作出分布 → 只用 I5 合成示教 + mode token，不手工写轨迹；
  - 假触发伤成功 episode → 滞回 + 净收益门禁 + 标称集「不伤害」测试；
  - 块内开环导致恢复太晚 → `T_a` 取 4–8；在预接触段用「小步/柔顺」的标称块降低接触力。

### 1.1 VTO：指令-实际残差 → 虚拟力矩 → 接触/滑移

```python
class VirtualTorqueObserver:
    def __init__(self, dyn_model, kp0, dp0, hist=8):
        self.cmd_buf = deque(maxlen=hist)      # (t, q_cmd_l, q_cmd_r, grip_cmd)
        self.kp, self.dp = kp0, dp0
        self.dyn = dyn_model                    # URDF 刚体动力学或学习残差
        self.head = ContactHead()               # 0.1M 参数，VLA 辅助头/同服务小头

    def observe(self, obs, now):
        ql = obs["observation.state.left_arm"][-1]
        qr = obs["observation.state.right_arm"][-1]
        cl, cr = self._align_cmd(now)           # 与观测时间对齐的指令
        rl, rr = cl - ql, cr - qr
        qdl = diff(obs["observation.state.left_arm"])
        qdr = diff(obs["observation.state.right_arm"])
        taul = self.kp * rl + self.dp * (self._cmd_vel_l() - qdl) - self.dyn.tau(ql, qdl)
        taur = self.kp * rr + self.dp * (self._cmd_vel_r() - qdr) - self.dyn.tau(qr, qdr)
        feat = concat(taul, taur, rl, rr,
                      obs["observation.state.left_gripper"][-1],
                      obs["observation.state.right_gripper"][-1],
                      ee_vel(obs), visual_proximity(obs))
        p_c, p_s, dir_c = self.head(feat)
        return ContactState(p_c, p_s, taul, taur, dir_c)

    def _align_cmd(self, now):
        # 指令由我们自己发，时间戳精确；±1 步搜索吸收 evaluator 抖动
        return nearest(self.cmd_buf, now)
```

### 1.2 CEFC：reset/首块的本体自校准

```python
class CrossEmbodimentCalibrator:
    def __init__(self, prior):
        self.prior = prior          # q_offset=0, alpha=1, table_h, cam
        self.token = prior.copy()

    def update(self, obs, vto, step):
        # 只用 episode-local 观测；默认不跨 episode 缓存
        if step == 0:
            self.token.q_offset = estimate_offset_from_home(obs)
            self.token.table_h  = estimate_table_height(obs, self.token.q_offset)
            self.token.cam_norm = estimate_camera_norm(obs)
        if step <= 2 and vto.free_space_likely():
            # 自由空间段：用已知重力项反解 K_p 尺度 alpha_i
            self.token.alpha = robust_fit_stiffness_scale(
                obs, vto.cmd_buf, self.token.q_offset)
        self.token.theta_c = self.prior.theta_c / max(self.token.alpha, 0.5)
        return self.token

    def normalize_obs(self, obs, token):
        o = obs.copy()
        o["observation.state.left_arm"]  = obs["observation.state.left_arm"]  - token.q_offset_l
        o["observation.state.right_arm"] = obs["observation.state.right_arm"] - token.q_offset_r
        o["observation.state.left_ee_pose_gripper_base"]  = to_table_frame(obs[...], token)
        o["observation.state.right_ee_pose_gripper_base"] = to_table_frame(obs[...], token)
        return o
```

### 1.3 FCR：块边界的力条件恢复

```python
class ForceConditionedRecovery:
    MODES = ["continue", "slow", "re_approach", "re_grasp", "retreat"]

    def __init__(self, policy, vto, calib, margin=0.1):
        self.policy, self.vto, self.calib = policy, vto, calib
        self.margin = margin
        self.hist = deque(maxlen=2)
        self.step = 0

    def get_action(self, obs):
        token = self.calib.update(obs, self.vto, self.step)
        obs_n = self.calib.normalize_obs(obs, token)
        cs = self.vto.observe(obs_n, self.step)
        self.hist.append(cs)

        mode = "continue"
        if self._persistent(cs) and self._net_gain(mode="recover") > self.margin:
            if cs.p_slip > 0.7:
                mode = "re_grasp"
            elif cs.p_contact > 0.8 and self._no_progress():
                mode = "re_approach"
            elif cs.p_contact > 0.8:
                mode = "slow"
        elif cs.p_contact > 0.9 and self._collision_likely():
            mode = "retreat"

        chunk = self.policy.propose_chunk(obs_n, mode=mode, prior=self.prior)
        chunk = self._smooth_and_clamp(chunk)
        self.vto.push_cmd(self.step, chunk)     # 缓存自己刚发的指令
        self.step += 1
        return chunk

    def _persistent(self, cs):
        return all(c.p_contact > 0.6 for c in self.hist) and len(self.hist) == 2
```

### 1.4 多端口：共享权重 + 每端口独立标定/历史

```python
class MultiPortServer:
    def __init__(self, n_ports, shared_backend):
        self.backend = shared_backend           # 只读权重，无状态推理
        self.ports = [PortState(calib=CrossEmbodimentCalibrator(prior),
                                vto=VirtualTorqueObserver(...),
                                hist=deque())
                      for _ in range(n_ports)]  # 每端口独立，绝不共享

    def handle(self, port, obs):
        st = self.ports[port]
        # reset() 清 episode 状态；标定 token 默认每 episode 重估
        return st.policy_step(obs, self.backend)
```
