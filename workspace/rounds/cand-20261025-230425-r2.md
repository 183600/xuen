# 第 8 轮（新循环第 2 轮）· CACTUS-GPR：最后三厘米不是“放”，是“接触”

> 检索/复核日期：**2026-10-25（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「云端协同」「真实世界泛化」「多传感器融合」。
>
> **结论先行**：上一轮把终局从“泛放置”收窄到“终局放置”，方向是对的，但还差一层。占位榜的逐任务数据（只能当弱先验）显示，真正难的不是“把东西放到桌上”，而是**接触密集的终局操作**：插网线、插插头、开锁、拉拉链、合盒盖、挂杯子、叠碗、拧瓶盖、折毛巾。它们同时是成功闸门、这些任务内部步骤分的关键权重、以及五个泛化轴都要经过的最后一关。更关键的是：**官方 API 没有力/力矩/电流/触觉，只有 4 路 RGB + 本体感受 + 语言**。所以本轮的主线不是“再换一个更大的 VLA”，而是把“接触”从不可观测量变成可估计量：用**本体跟踪残差 + 视觉流残差 + 夹爪状态**构造准接触信号，用**阶段路由的四视角几何融合**补几何，用**云端单 checkpoint 双时标/自验证 TTC**补闭环，用**轴感知 + 机器人指纹**处理真实世界泛化。简称 **CACTUS-GPR**：Contact-Aware Cloud-edge Tactile-free Unified System。
>
> 先澄清一个命名：这里的 “edge” **不是**在机器人端跑模型——API 只让我们返回动作，机器人端没有我们的推理进程。真正的“云边协同”是**云端策略与机器人底层伺服的时间协同**：我们控制的是云端快慢双路、动作 chunk、异步预计算和多端口服务；机器人端只负责执行。这个约束贯穿全文。
>
> **一句话**：把“接触”当成一等观测，专攻 20/32 个接触密集终局任务；这是跨五轴、且不被单模型规则反噬的最高杠杆。

## 0. 本轮先核实：八个事实

### 0.1 榜单仍是占位，但逐任务结构提供了弱先验

- `leaderboard.html` 仍显示「即将发布 / Coming Soon」；`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`；`runs.html` 是 256/256 条占位记录；`details.html` 明确写「测试视频占位 Placeholder video」。[S3][S4][S5][S6]
- 8 个占位模型：MolmoAct2 29.7/39.0（44.02s）、WALL-OSS-0.5 28.5/38.9、DreamZero 27.9/37.9、Spirit-v1.5 25.9/34.4、DM0 23.5/31.7、PI-0.5 22.8/30.6、GigaBrain-0 22.6/29.5、GR00T N1.5 20.5/28.1。均值约 25.2% 成功 / 33.8% 步骤分，步骤分比成功率高约 **8.6pp**。
- **这些数字不能用来判断谁强谁弱**，也不能证明真实榜单的分布。唯一可谨慎使用的是两个结构先验：(a) 8 个模型都落在 20–30% 区间，说明没有“通用解法”；(b) 步骤分显著高于成功率，说明大量失败发生在“做了大部分步骤、倒在后面”。

### 0.2 逐任务预览把“难点”从“放置”推到了“接触”

按 8 个占位模型逐任务平均成功率排序，最难的一批是：

| 任务 | 平均成功率 | 平均步骤分 | 终局动作类型 |
|---|---:|---:|---|
| Plug In Ethernet（T26） | 17.7 | 23.7 | 插入网口 |
| Unlock（T12） | 20.1 | 26.9 | 拧钥匙/翻金属环 |
| Spell robot（T22） | 21.8 | 29.3 | 字母放到板上 |
| Organize Stationery（T17） | 22.5 | 30.1 | 合上笔盒 |
| Open Pill Bottle（T14） | 22.7 | 30.5 | 拧盖+倒药 |
| Hang the Cup（T01） | 23.0 | 30.8 | 挂到杯架 |
| Pick Out Battery（T11） | 23.3 | 31.2 | 从积木中挑出 |
| Zip Up（T19） | 23.4 | 31.3 | 拉拉链 |

最容易的一批是 Stack Cups 30.3、Conveyor Food Sorting 29.1、Store Earphones 27.9、Fruit Basket Collection 27.8、Place Photo Frames 28.0、Paper Cup Stacking 28.0。MolmoAct2 自己的最低项则是 Disconnect Ethernet 21.3、Pick Out Battery 23.5、Unlock 23.5、Place Photo Frames 24.3、Organize Pencil Case 24.9、Fold Towel 27.2、Pack Phone 27.4、Hang the Cup 27.3。

这个模式**不是干净的**：Place Photo Frames 的平均成功率不低，但头部模型很低；Spell robot 也不完全是接触任务。它只能说明“接触密集终局”是**最可疑的失败簇**，不能单独证明因果。真正的证据要来自调试槽的步骤级诊断（产物区 §7.2）。但它足以把本轮的主假设从“放置”改成“接触”。

### 0.3 规则把优化目标钉死：成功率优先，320 trials，单模型

参赛手册已核实（[S8][S9]）：

- 每个任务 10 次独立运行，覆盖 5 类泛化（位置、干扰物、桌面背景、未见物品、人为干扰），每类 2 次；32 任务共 **320 trials**。
- 实时榜单按 **32 任务总平均成功率**排序；成功率相同按平均步骤分；仍相同按提交日期较早。
- 单次真机执行上限 **180s**，超时失败，并按执行情况计步骤分。
- **所有任务须基于同一模型，不得混合多个模型**；World Model、VLA 均可。
- 评测在**多台机器人**上进行；模型由选手远程部署，平台只调用 API。
- 不计分单任务调试通道存在，但次数/成本未公开。

这意味着：**成功率是主目标，步骤分是破同分项；终局步骤是 32/32 任务的闸门**。任何“只提步骤分、不提成功率”的优化，排名收益都有限。

### 0.4 API 的“传感缺口”是本轮最重要的约束

提交接口 v2（[S10]）的观测目录只有：

- 4 路 RGB：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`，原生 480×640；
- 双臂 7+7 关节、左右夹爪开度、15 维下半身；
- 左右 EE 位姿（base 系，xyz+rpy）；
- `observation.language` 单字符串（episode 内不变）；
- `obs_delta_indices` 选键/堆叠、`image_resize` 缩放、`action_chunk_size` 固定 chunk、`control_space=joint|ee`；
- N 个连续端口（从 8765 起），每台机器人一个端口，端口间状态隔离。

**没有力、力矩、电流、触觉、深度图、相机内参/外参、物体位姿。** 这是本轮所有设计的起点：接触必须从“位置 + 视觉 + 夹爪”里推断，不能假装有力传感器。

### 0.5 数据足够训练多视角/本体感受，但没有接触标签

- Collection 32 个数据集，约 **33k episodes / 169h**；[S11]
- HangCup 实测 1,043 episodes / 194,564 frames / 30fps；[S12]
- 四路相机：`head_stereo_left/right` + `wrist_left/right`；EE 位姿在 base 与 torso 两套坐标；含 `state_d435`、lower_body；每任务 5 条英文复述（`@` 分隔）；
- `lastModified=2026-10-14`，全量发布是最近两周内的事。

相机键与 API 键的映射是**推断**：`head_stereo_left→cam_left_high`、`head_stereo_right→cam_right_high`、`wrist_left→cam_left_wrist`、`wrist_right→cam_right_wrist`。需要标定/官方确认；但至少训练数据与评测观测在语义上对齐。

数据里没有接触/力/滑移标签，也没有“机器人指纹”。这决定了 VFS 必须用**自监督 + 弱标签 + 小规模真机校验**，不能监督式地学一个“力回归”。

### 0.6 评分结构：终局是闸门，接触密集终局是“闸门中的闸门”

官方 32 任务 `score_steps` 满分统一 100，合计 3200 分；上一轮已抓全 32/32（[S2]）。关键聚合：

- 全部终局步骤合计 **1275/3200 = 39.8%**；
- 放置/插入/堆叠/闭合类步骤约 **1910/3200 = 59.7%**（关键词粗分）；
- 按“终局动作是否涉及插入/拔出/拧转/闭合/悬挂/堆叠/折叠/倾倒/挑出”粗分，**20/32 任务**属于接触密集终局；它们的终局步骤合计 **775/3200 = 24.2%**，但对应 **62.5% 的成功 trials**。
- T27 是典型：放碗 30 + 叠第二个 30 + 叠第三个 40；T10 是抓插排 30 + 抓插头 30 + 插入 40；T12 是拿锁 30 + 拧钥匙 30 + 翻环 40。

**20/32 是本轮人工分类，不是官方标签**。T07（相框摆正/开支架）、T13（试管插架）可争议；保守不计入。即使只有 16/32，杠杆仍然成立（§4.2）。

### 0.7 调试槽是唯一可信的真机步骤级反馈

`profile.html`（[S7]）明确两种提测：计分多任务（32 任务、进榜）和不计分单任务调试（1 个任务、不进榜、预约时段、管理员确认）。这比自建孪生更可信，但次数/成本未知。本轮把它当**发布门**，不是调参器：每个大版本最多 1 个槽，优先 T26/T12/T19/T27/T10。

### 0.8 外部证据链：本轮不是凭空转向

- **ManipArena**（[S16]）：20 任务、10,812 条专家轨迹、188h 真机；最佳 tabletop 配置 951/1500（63.4%）；多任务训练让 π0.5 626→703，却让 WALL-OSS 951→865；200/task 的平衡数据优于 ~500/task。**结论：真机结论取决于模型来源、微调 regime、数据采样和标注粒度，不是“多任务一定更好”。**
- **CloudEdgeVLA**（[S17]）：云慢特征 + 轻量 edge head；40-step 均匀延迟下仍保持 63.8–78.0%，VLASH 最多 6.4%，单路径基线最多 3.0%。
- **MVUCF**（[S18]）：训练期注入多视角几何（深度查询 + 跨视角对应），部署时移除深度/标定/辅助头，仍保持 RGB-only、无额外推理 FLOPs；LIBERO 98.9%、LIBERO-Plus +22.4、六个 RoboTwin 任务 +23.3。
- **FocusVLA**（[S19]）：阶段感知的多视角路由，真实世界 71.7→85.0（+13.3 over π0.5），RoboTwin +10.10pp；说明“静态拼接多视角”不够。
- **Self-Adaptive VLA**（[S20]）：用自身 rollout 的上下文 token 适配硬件偏移（执行器偏置、关节编码器偏移），恢复 >80% 基础策略性能；对应 N 台机器人的隐藏硬件轴。
- **VT-WAM**（[S21]）：视觉-触觉世界动作模型在 6 个接触密集任务 71.67%，比 Fast-WAM +26.67pp；触觉确实有用，但 UniBot 没有。
- **NeuralActuator**（[S22]）：无 F/T 传感器的外力/接触估计，但依赖执行器遥测（电流/力矩等）；UniBot 不提供。**这条路走不通，必须换。**
- **Think Like a World Model**（[S23]）：把世界模型特征蒸馏进 0.8B 学生，LIBERO 97.9%、RoboCasa-GR1 48.2→50.5%，部署 32ms/1.86GB（RTX5090），与基线完全一致；适合“训练期世界模型、推理期单 VLA”。
- **DiVeR**（[S24]）：决策关键状态的 verifier 学习，用采样动作离散度重加权；测试时扩展在 LIBERO/RoboCasa/真机稳定增益。
- **VLASH / RTC / VLA-RAIL**（[S25][S26][S27]）：异步推理、未来状态滚动、chunk 拼接/平滑；VLASH 最高 2.03× 加速、17.4× 反应延迟降低；RTC 无需训练改动；VLA-RAIL 把 5–10Hz 推理与 200–1000Hz 控制解耦。

## 1. 思考轨迹：我怎样从“放置”走到“接触”

这一节是过程，不是结论。把它写出来，是为了让下一轮能沿着同一条证据链接力，而不是重复 search。

1. **从第 7 轮的“放置是闸门”出发。** 第 7 轮的算术是对的：终局步骤是 32/32 任务的闸门，且跨五轴。但它把“终局”当成一个同质的“放置”类别。占位榜的逐任务数据一拉，问题就出来了：真正低分的不是所有放置，而是插、拔、拧、拉、合、挂、叠、倒这些**接触密集**动作。放置是上位词，接触才是失败机制。
2. **先查 API，确认“接触”是不是可观测。** 结论是没有力/力矩/电流/触觉，也没有深度和标定。第一反应是“加触觉/加力传感器”，但这在官方评测里不可行：我们改不了评测硬件，API 也不会把触觉传进来。**这条死路必须早砍。**
3. **再查无传感器力估计。** NeuralActuator 证明可以从执行器遥测估计外力，但 UniBot 只给关节位置/EE 位姿，不给电流/力矩；用不了。第二反应是“用跟踪误差当力”，但原始跟踪误差会被控制器刚度、重力、摩擦、延迟污染。于是改成**学习式本体动力学预测 + 残差**：在自由空间，预测残差小；接触时，残差大。再加上视觉流残差和夹爪 stall，构成“准接触”。这不是力估计，是接触/滑移的概率观测。
4. **再查多视角。** 4 路相机看起来很多，但现有 VLA 多半是静态拼接；FocusVLA 证明模型会“偷懒”依赖腕部视角，阶段路由能显著提成功率；MVUCF 证明训练期几何注入可以在部署时完全去掉深度/标定头，保持 RGB-only。于是决定：**不引入外部 SAM/深度模型**（单模型审计风险），而是把几何/对应/深度作为训练期辅助目标，把阶段路由作为单 checkpoint 内的一个小模块。
5. **再查云端协同。** 一开始想“云边分层”，但 API 不允许机器端跑模型；所谓 edge 只能是机器人底层伺服。于是把“云边”重新定义为：云端策略 + 机器人底层控制的时间协同。VLASH 的“用上一个 chunk 滚动未来状态”正好适配 request-response API：机器人执行 chunk 时，服务器可以预计算下一个 chunk；下一次调用再用真实观测校正。RTC 负责 chunk 拼接，VLA-RAIL 负责平滑。**这不是“把模型放边缘”，而是“把等待时间藏进预测里”。**
6. **再查真实世界泛化。** ManipArena 给了一个冷水：多任务训练不一定更好，WALL-OSS 从 951 掉到 865；数据平衡、来源、微调 regime 都会改变结论。加上 API 明确 N 台机器人，硬件偏移是隐藏轴；Self-Adaptive VLA 证明上下文 token 可以恢复 >80%。于是决定：不做“每任务专家/每轴专家”（单模型审计 + 数据碎片化），做**轴感知的上下文调制 + 每机器人指纹校准**；L2L 外部数据默认关闭。
7. **再查世界模型。** DreamZero 14B/7Hz 很强，但推理太重，不适合 30Hz 接触闭环；Think Like WM 证明可以只蒸馏特征、部署与基线完全一致（32ms/1.86GB）。于是把世界模型降为**训练期可选项**，不进主路径；主路径仍是单 checkpoint + 辅助头。
8. **最后合成。** 把“接触”作为主线，把 SSG/PGL/OPT/ICR/SVL 重新接到接触上；把 DTI/TTC/AXIS 作为使能器；把外部模型、第二 verifier、每任务 LoRA、全孪生、运行时仿真/MPC 全部砍掉。形成 CACTUS-GPR 与 H1–H3。

## 2. 三个灵感词，各自钉到事实上

### 2.1 云端协同：不是“上云”，是“把等待藏进预测里”

UniBot 的评测形态决定了“云”是唯一算力：模型在我们自己的服务器，平台通过远程 API 调用；机器人端只执行。于是云端协同有三个具体问题：

1. **单次决策延迟 vs chunk 执行时间。** 若 chunk=8、控制 30Hz，一个 chunk 只有 267ms；chunk=16 是 533ms。模型前向 + 网络 + 观测传输必须落在这个窗口内。MolmoAct2/WALL-OSS 这类 4–6B 模型在单卡上是百毫秒级；多视角、TTC 会进一步吃预算。**不能假设“云上无限算力”**。
2. **请求-响应之间没有连续观测。** 平台执行完一个 chunk 才调用下一次 `get_action`；我们拿不到执行中间的帧。因此“异步”只能是**服务器侧预计算**：用上一个 chunk 把机器人状态向前滚（VLASH），先算一个候选 chunk；下次真实观测到达时再校正/选择（RTC 拼接）。这能隐藏一个 chunk 的等待，但不能做到真正的连续流。
3. **N 台机器人共享后端。** README 要求暴露 N 个连续端口，每端口一个 episode、状态隔离；可以每端口独立进程，也可以共享权重 + 每端口 KV/状态 + 批处理。共享后端省显存，但并发会抬高 p99；接触阶段需要优先级。

对应的设计是 **DTI（Dual-Timescale Inference）**：单 checkpoint 内做快/慢两路——慢路用完整 VLA 出高质量 chunk，快路用同一 checkpoint 的浅层/小 action head 在接触阶段做低延迟修正；配合 VLASH 式预计算和 RTC 式拼接。**不是第二个模型，不是边缘部署。**

### 2.2 真实世界泛化：接触是“跨轴不变量”

官方五轴是位置、干扰物、背景、未见物品、人为干扰；API 还暴露了第六个隐藏轴——**多机器人硬件差异**（执行器偏置、编码器偏移、相机安装差异）。第 7 轮把“补最弱轴”改成“攻终局放置”，本轮再进一步：

- **接触信号对五轴更不敏感。** 背景换了、物体颜色变了、位置挪了，但“插头进插座”的物理接触过程不变；跟踪残差、视觉流残差、夹爪 stall 仍然存在。外观中心的检索/策略会崩，接触中心的观测不会。
- **但接触信号对硬件很敏感。** 关节零位/摩擦/刚度不同，跟踪残差的基线就不同；所以必须做每机器人指纹/基线校准，否则“接触”会被误判成“自由空间”。
- **多任务不一定更好。** ManipArena 的 WALL-OSS 951→865 是警告：把 32 任务混在一起训练可能伤害强底座。要用任务平衡采样、来源分层、held-out 轴诊断，而不是盲目堆数据。
- **世界模型可以补物理泛化，但只做训练期。** Think Like WM 的 0.8B 学生 + 特征蒸馏是低风险路径；DreamZero 14B/7Hz 不适合运行时。

对应设计是 **AXIS-HW + WM-D**：轴感知的检索/视角/阈值调制，每机器人指纹的 AdaLN/动作校正，可选的 world-model 特征蒸馏。**不做每轴专家、不做每任务 LoRA。**

### 2.3 多传感器融合：不是“更多传感器”，是“把现有传感器的物理量榨干”

API 的传感器组合是固定的：4 路 RGB + 本体 + 语言。真正的融合问题不是“加什么”，而是“怎么把接触从这些信号里挤出来”。

| 模态 | 能提供什么 | 主要失效 | 本轮用法 |
|---|---|---|---|
| 双目高位（左/右） | 全局几何、目标/容器位置、桌面布局 | 遮挡、背景变化、标定缺失 | 训练期几何注入 + 阶段路由；不依赖运行时深度模型 |
| 左右腕部 | 局部接触、插入对准、滑移、夹爪-物体关系 | 视野窄、运动模糊、透明物体 | 接触阶段主视角；视觉流残差；插入深度 |
| 本体（关节/EE/夹爪/下半身） | 运动学、跟踪误差、夹爪 stall、基座稳定 | 控制器刚度/摩擦/延迟污染 | 学习式动力学预测残差 = 本体 surprise |
| 语言 | 任务/步骤语义、5 条复述 | 歧义、未见复述 | SSG 步骤图 + 任务条件 |
| 时间（帧堆叠/历史） | 速度、接触 onset、滑移 | 延迟、丢帧 | 滑窗 + 异步预计算 |

融合结构是 **MSF-3D + VFS**：MSF-3D 把四视角 + 本体变成阶段路由的 3D 场景 token；VFS 把本体预测残差 + 视觉流残差 + 夹爪状态变成接触/滑移/插入深度 token。两者都进同一个 checkpoint，不引入外部模型。

## 3. 失败模型：从 P1–P6 到 C1–C8

第 7 轮的 P1–P6 仍然有效，但“接触”需要更细的失败模式：

| # | 失败模式 | 观测/证据 | 对策 |
|---|---|---|---|
| C1 | 目标/容器 grounding 错（选错槽位/位置） | Spa-Bench、AnySlot、SpaceVLA；PlacePhotoFrame 低分 | SSG + PGL + MSF-3D |
| C2 | 接近路径碰撞（拿着物体撞容器/干扰物） | 官方 human 备注多为平移干扰 | 3D 场景 token + 碰撞感知接近 |
| C3 | 姿态不对（叠碗不平、插头歪、相框没摆正） | 评分步骤明说 straighten/order | OPT 位姿迁移 + 腕部伺服 |
| C4 | 释放过早/过高（掉落/弹跳/滚动） | 终局权重最大；步骤分高但成功率低 | SVL settle + 缓放 |
| C5 | **插入/闭合深度不够（接触核心）** | T26/T10/T12/T19/T31 低分 | VFS 接触/插入深度 + 柔顺小步搜索 |
| C6 | 不验证就以为完成（掉了也不知道） | 成功=全步骤；无自动 verify | SSG 谓词 + SVL + TTC |
| C7 | **接触/滑移不可见（新）** | API 无 F/T；透明/小件；夹爪 stall | 本体 surprise + 视觉流残差 + 夹爪 stall |
| C8 | **硬件/延迟偏移（新）** | N 机器人；Self-Adaptive；云延迟 | AXIS-HW + DTI + 每机器人基线 |

C5/C7 是本轮的新核心；C1–C4/C6 由第 7 轮的组件继续承接；C8 是“云端协同 + 真实世界泛化”的交叉点。

## 4. 主判断：接触是新的“放置”，杠杆更大

### 4.1 为什么不是“再换一个更大的 VLA”

- 占位榜 8 个模型都在 20–30%，没有哪个架构碾压；说明瓶颈不是“模型不够大”，而是**任务结构里的接触段没有被显式建模**。
- MolmoAct2 的空间/具身推理、WALL-OSS 的 20+  embodiment 预训练、DreamZero 的世界模型都很强，但都没有“无力/触觉 API 下的接触观测”这一层；这正是可差异化的位置。
- ManipArena 说明多任务训练可能伤害强底座（WALL-OSS 951→865）；盲目换更大底座/更多数据，收益不确定。
- 单模型规则堵住了“每任务专家/第二 verifier/外部感知模型”的捷径；必须把能力做进**一个 checkpoint**。

### 4.2 杠杆算术：20/32 任务，62.5% 的 trials

设接触密集终局任务数为 n，任务占比 f=n/32；Δ 为这些任务的终局成功率提升；q 为“到达接触阶段的条件通过率”（不是终局成功率，而是能走到接触段的概率）。全局成功率增益近似：

```text
Δ_global ≈ Δ × f × q
```

| 方案 | 作用范围 | Δ=10pp, q=0.6 | Δ=15pp, q=0.6 | Δ=15pp, q=0.8 |
|---|---:|---:|---:|---:|
| 单轴改造（不乘 q） | 1/5 = 20% | +2.0pp | +3.0pp | +3.0pp |
| n=16 接触任务 | 50% | +3.0pp | +4.5pp | +6.0pp |
| **n=20 接触任务（本轮）** | **62.5%** | **+3.75pp** | **+5.6pp** | **+7.5pp** |
| n=24 接触任务 | 75% | +4.5pp | +6.75pp | +9.0pp |

在 Δ=15pp 下，只要 n≥16 且 q≥0.6，接触主线的收益就 ≥ +4.5pp，已经高于“单轴 +15pp”的 +3pp。20/32 是本轮的人工分类；即使保守到 16/32，赌注仍然成立。**这就是为什么它比“再补一个泛化轴”更值得押。**

注意：20 个接触密集终局的步骤分只占 775/3200=24.2%，不是 39.8%；39.8% 是全部 32 个终局步骤。但排名**先看成功率**，而 62.5% 的 trials 都要过这些终局闸门；步骤分是破同分项，不是主目标。不要把 24.2% 和 62.5% 混为一谈。

### 4.3 三个可证伪假设

- **H1（失败簇）**：在 UniBot 上，接触密集终局的失败率显著高于同任务的前置抓取/放置段；调试槽的步骤级诊断能复现这个差距。若不能，回到第 7 轮的“放置”主线。
- **H2（准接触可学）**：本体动力学 surprise + 视觉流残差 + 夹爪 stall 能在官方数据上达到 contact F1 ≥0.65、slip F1 ≥0.55，并且增益在五个泛化轴上同向；若只在背景轴有效，退回纯视觉。
- **H3（闭环可部署）**：单 checkpoint 的快/慢双路 + VLASH 式预计算 + RTC 拼接，能把接触阶段的有效反应延迟压到一个 chunk 内（chunk=8 时 <267ms，chunk=16 时 <533ms），且不需要第二个模型；若 p99 超窗，降 TTC K 或关闭快路。

### 4.4 与第 7 轮的关系：保留骨架，换主武器

| 关系 | 内容 |
|---|---|
| 保留 | SSG 步骤图、PGL 目标阶梯、OPT 位姿迁移、ICR 检索、SVL 落点闭环、GPR-VLA/WLA 底座、TLE/ACP/GF、AH-TP、Endurance Governor、Compliance Compiler、DebugLoop |
| 升级 | SSG 加接触相位；PGL 用 MSF-3D 的 3D 容器/目标；OPT 加接触感知释放高度/速度；ICR 改成几何/运动键 + 同 checkpoint 文本编码；SVL 升级为 contact-aware servo；NRB 加接触失败恢复 |
| 新增 | MSF-3D、VFS、DTI、TTC-SV、AXIS-HW、WM-D、接触数据协议 |
| 降级 | L2L 外部数据（默认 OFF，规则未知）；TCLB（离线比较）；FLEET（工程检查单，不是研究轴） |
| 砍掉 | 每任务 LoRA/模型合并；全 32 任务高保真孪生；运行时仿真/MPC；仿真 RL；布料/拉链/透明全物理；WMA-0 进主路径；**推理期外部 SAM/深度/检测模型**；**第二 verifier 模型**；**每轴专家模型** |

## 6. 风险、合规与“先立后破”

- **规则未读部分**：手册第 2.2 节之后未完整抓到；外部数据、开源权重、调试槽费用、步骤分聚合公式仍未知。L2L 默认 OFF；邮件确认后再开。
- **单模型审计**：所有学习组件（VLM、action expert、depth/correspondence/contact/slip/value 头）必须在唯一 checkpoint 内；SSG/PGL/SVL 是确定性代码；ICR 是数据；世界模型只做训练期 teacher；推理期不调用 SAM/深度/检测/第二 verifier。模型卡逐项披露。
- **接触信号可能太弱**：跟踪残差受控制器刚度/摩擦/延迟污染；用学习式动力学预测、视觉流、夹爪 stall 三路互补；contact F1 <0.6 就关闭 VFS，退回第 7 轮的 SSG+PGL+SVL。
- **标定缺失**：API 不给内参/外参；MSF-3D 用训练期几何注入 + 单目/腕部回退；容器位姿误差 >1cm 就退出 OPT，改用 2D 锚点伺服。
- **延迟**：chunk=8 只有 267ms；TTC K=4 可能超窗。快路只在接触阶段开，K 自适应；p99 超窗就降 K/关 TTC。
- **单模型 vs 检索**：ICR 的键必须是几何/运动/同 checkpoint 文本编码，不能用独立编码器；否则审计风险。
- **统计噪声**：320 trials，p≈0.3 时 SE≈2.56pp；+3pp 才约 80% power；+5pp 才约 90%。不要用一次调试槽的 +10pp 当结论。
- **占位榜不可信**：所有排名/差值只当弱先验；真实榜单发布后重跑 H1。
- **安全**：没有力控，只有位置限制 + 小步搜索；不做大力挤压；关节限位/总时长守卫兜底。

## 7. 一句话押注

**本轮押注 CACTUS-GPR：接触密集终局是 20/32 任务（62.5% trials）的成功闸门，而官方 API 恰好没有力/触觉；用“本体 surprise + 视觉流残差 + 夹爪 stall”的准接触观测去补这个缺口，比换更大的 VLA 或再补一个泛化轴更划算。**

| 泛化 | 五轴 + L2L 数据 | **轴感知 + 机器人指纹** | N 台机器人；ManipArena 警告多任务可能伤害强底座；外部数据规则未知 |
| 模型 | 单 checkpoint + SSG/PGL | **单 checkpoint + 辅助头** | 单模型规则；不引入外部 SAM/深度/第二 verifier |
| 数据 | 33k + 合成 | **33k + 接触/几何标签 + 平衡采样** | 合成接触不可靠；ManipArena 显示 200/task 平衡可优于更大规模 |
| 评测 | TCLB + 调试槽 | **接触专项调试槽 + 两次计分跑** | 步骤级诊断才能验证 H1 |

### 1.3 规则：成功率优先，320 trials，单模型

手册（[S8][S9]）已核实：

- 每任务 10 次独立运行；5 类泛化（位置/干扰物/背景/未见物品/人为干扰）各 2 次；32 任务共 **320 trials**。
- 实时榜单按 **总平均成功率**排序；相同按总平均步骤分；仍相同按提交日期较早。
- 单次真机上限 **180s**；超时失败，并按执行情况计步骤分。
- **同一模型完成全部 32 任务，不得混合多个模型**；World Model、VLA 均可。
- 多台机器人评测；模型由选手远程部署；平台只调用 API。
- 不计分单任务调试通道存在；次数/成本未公开。

**推论**：优化目标不是“步骤分最大化”，而是“先过成功闸门，再争步骤分”。终局步骤是 32/32 任务的闸门；接触密集终局是其中 20 个。

## 2. 评分与失败分析

### 2.1 排名数学

```text
成功率 = 32 任务平均成功率（主排序）
步骤分 = 32 任务平均步骤分（破同分）
320 trials = 32 × 10；5 轴 × 2
p≈0.3 时 SE = sqrt(0.3×0.7/320) ≈ 2.56pp
+3pp ≈ 80% power；+5pp ≈ 90% power（近似）
```

**任何小于 +3pp 的全局提升都可能是噪声**。这就是为什么本轮不把“换更大底座”当主赌注：没有 320 trials 的配对证据，无法证明 +2pp 的架构差异。

### 2.2 接触密集终局的杠杆

设 n 个接触密集任务，f=n/32；Δ=这些任务的终局成功率提升；q=到达接触阶段的条件通过率。全局成功率增益 ≈ Δ×f×q。

| 方案 | 作用范围 | Δ=10, q=0.6 | Δ=15, q=0.6 | Δ=15, q=0.8 |
|---|---:|---:|---:|---:|
| 单轴改造（不乘 q） | 1/5=20% | +2.0pp | +3.0pp | +3.0pp |
| n=16 | 50% | +3.0pp | +4.5pp | +6.0pp |
| **n=20（本轮）** | **62.5%** | **+3.75pp** | **+5.6pp** | **+7.5pp** |
| n=24 | 75% | +4.5pp | +6.75pp | +9.0pp |

在 Δ=15pp 下，只要 n≥16、q≥0.6，接触主线就 ≥ +4.5pp，高于单轴 +15pp 的 +3pp。20/32 是人工分类；即使保守到 16/32，赌注仍成立。q 需要用调试槽的步骤级数据校准；本轮先按 0.6–0.8 做敏感性分析。

### 2.3 失败模型 C1–C8

| # | 失败模式 | 观测/证据 | 对策 | 对应旧点 |
|---|---|---|---|---|
| C1 | 目标/容器 grounding 错 | Spa-Bench/AnySlot/SpaceVLA；PlacePhotoFrame 低分 | SSG+PGL+MSF-3D | P1 |
| C2 | 接近路径碰撞 | 官方 human 备注多为平移干扰 | 3D 场景 token + 碰撞感知 | P2 |
| C3 | 姿态不对 | 评分步骤写 straighten/order | OPT + 腕部伺服 | P3 |
| C4 | 释放过早/过高 | 终局权重最大；成功低/步骤高 | SVL settle + 缓放 | P4 |
| C5 | **插入/闭合深度不够** | T26/T10/T12/T19/T31 低分 | VFS + 柔顺小步搜索 | P5 |
| C6 | 不验证就以为完成 | 成功=全步骤 | SSG 谓词 + SVL + TTC | P6 |
| C7 | **接触/滑移不可见** | API 无 F/T；透明/小件；夹爪 stall | 本体 surprise + 视觉流 + 夹爪 | 新增 |
| C8 | **硬件/延迟偏移** | N 机器人；Self-Adaptive；云延迟 | AXIS-HW + DTI + 基线校准 | 新增 |

### 2.4 模型路线：为什么不是简单换底座

| 模型 | 路线/强项 | 对 UniBot 的弱项 | 本轮用法 |
|---|---|---|---|
| MolmoAct2 | 开源、空间/具身推理、adaptive depth、流匹配 action expert、双机械臂数据 | 无接触观测；多视角/延迟需工程 | **默认底座候选**（约 5.5B，模型卡） |
| WALL-OSS-0.5 | 4B、3B VLM 骨干、20+ embodiments、>1M trajectories/epoch、零样本真机 | ManipArena 多任务微调 951→865，强底座可能被多任务伤害 | **challenger**；必须做 bake-off |
| DreamZero | 14B WAM、视频扩散、7Hz、OOD 泛化 2× | 太重/太慢，不适合 30Hz 接触闭环 | 训练期 teacher/离线分析，不做运行时 |
| GR00T N1.5 | 人形 VLA | 占位榜最低 20.5；数据/对齐不足 | 人形 baseline |
| π0.5 | 通用 VLA；ManipArena 多任务 626→703 | 接触段无显式建模 | 对照 baseline |
| Spirit/DM0/GigaBrain | 占位模型 | 信息不足 | 不分析，避免臆测 |

结论：**底座只决定上限的一部分；接触观测/闭环是当前更稀缺的差异化**。默认用 MolmoAct2 与 WALL-OSS 做 8 任务 bake-off，胜者进主训练；GR00T/π0.5 只做对照。

### 2.5 三个可证伪假设

- **H1（失败簇）**：接触密集终局的失败率显著高于同任务前置抓取/放置段；调试槽步骤级诊断可复现。若不能，回退第 7 轮“放置”主线。
- **H2（准接触可学）**：本体动力学 surprise + 视觉流残差 + 夹爪 stall 在官方数据上 contact F1 ≥0.65、slip F1 ≥0.55；增益在五轴同向。若只在背景轴有效，退回纯视觉。
- **H3（闭环可部署）**：单 checkpoint 快/慢双路 + VLASH 式预计算 + RTC 拼接，把接触阶段有效反应压进一个 chunk（8→267ms，16→533ms），无需第二模型。若 p99 超窗，降 TTC K/关快路。

### 2.6 为什么比第 7 轮更该做

第 7 轮的“终局放置”已经是正确方向，但它的传感/控制设计仍是“视觉 + 位置”的泛化版：PGL/OPT/SVL 能解决“放得准”，却解决不了“插得进/合得上/拉得动”。本轮把研究问题从“目标位姿”推进到“接触状态”，并把云端协同从部署检查单变成时间闭环；这是同一路线上的加深，不是换题。

### 3.2 单 checkpoint：一个模型，多个头，两个 exit

**合规前提**：规则要求“同一模型，不得混合多个模型”。因此所有学习组件必须在同一个 checkpoint 内：

```text
θ = { VLM backbone, action expert,
      depth/correspondence heads,       # MSF-3D 训练期辅助；部署可丢弃
      contact/slip/insertion heads,     # VFS
      step predicate head,              # SSG
      value/progress head,              # TTC-SV
      axis/robot context head }         # AXIS-HW
```

- **慢 exit**：完整 VLM + action expert，出高质量 chunk；用于自由空间/远距离。
- **快 exit**：同一 backbone 的前 N 层 + 轻量 action head，出低延迟修正；用于接触/插入/闭合。训练时用慢 exit 蒸馏快 exit，推理时按相位选择。
- **不做**：第二 verifier、外部 SAM/深度/检测、每任务 LoRA、每轴专家。检索库是数据，不是模型；文本编码复用同一 VLM。
- **审计**：模型卡逐项列出头、训练数据、确定性代码、检索库；推理期不加载 teacher。

### 3.3 SSG：评分步骤图的接触升级

保留第 7 轮的 SSG，但把每个终局步骤拆成接触子相位：

```text
官方 step: "Plug the cable into the network port"
  → approach_port → align_plug → contact → insert(depth) → verify_seated
官方 step: "Zip up the pouch"
  → grasp_zipper → engage → pull(contact) → close → verify
官方 step: "Hang the cup"
  → approach_hook → align_handle → contact → hang → release → verify
```

- 输入：`score_steps`（32/32 已抓全）+ 5 条复述 + 中文描述。
- 图：线性 `s0→…→sk`，带权重 `w_i`；终局子相位继承终局权重。
- 运行：只有当 VFS/谓词/事件确认完成才前进；`human` 撤销触发回退。
- 输出：相位 token 给 MSF/VFS/SVL；重试预算按 `w_i` 分配。
- 谓词标签：规则/事件标签 + 演示统计；少量人工抽检。
- 风险：谓词噪声/语言未覆盖；用 160 条复述 + 嵌入兜底 + 调试试错。

### 3.4 MSF-3D：训练期几何注入 + 阶段路由

**目标**：在不依赖运行时深度/标定模型的前提下，让 4 视角 + 本体形成度量一致的 3D 场景表示。

- **输入**：4 路 RGB（高两位 + 腕两位）+ 本体（关节/EE/夹爪/下半身）+ 相位 token。
- **编码**：共享视觉 backbone + 相机/视角嵌入；高两位与腕两位分别 token 化；本体用 MLP 投影。
- **几何辅助（训练期）**：借鉴 MVUCF：
  - 坐标查询深度目标：让隐状态可解码出度量深度；
  - 跨视角对应目标：让不同相机看同一物理点的 token 对齐；
  - 预处理感知：训练时模拟 resize/裁剪/噪声，避免模型依赖固定分辨率。
  - 部署时移除深度/对应/标定头，保持 RGB-only、无额外推理 FLOPs。
- **阶段路由**：借鉴 FocusVLA 的未来意图路由，但用 SSG 相位做强先验：
  - approach/transport：高位双目权重高；
  - pre-grasp/contact：腕部权重高；
  - insertion/closure：腕部 + 本体权重高；
  - post-place/verify：高位 + 腕部。
  - 路由是软权重（可学习 gate + 相位 mask），不是硬切换；避免“腕部依赖惯性”。
- **3D token**：物体/容器 slot（位置、尺度、置信度）+ 夹爪 slot + 桌面平面；供 PGL/OPT/SVL 使用。
- **标定**：API 不给内外参；训练时用 `state_d435`/已知机器人几何做离线标定；若不可得，用单目相对深度 + 腕部近景；容器位姿误差 >1cm 时退出 OPT，退回 2D 锚点伺服。
- **证据**：MVUCF 在 LIBERO 98.9%、LIBERO-Plus +22.4、六个 RoboTwin +23.3，且训练期几何注入部署零开销；FocusVLA 真实世界 71.7→85.0。它们不是 UniBot 证据，但支撑“训练期几何 + 阶段路由”的方向。
- **风险**：多视角几何在透明/反光/小件上不稳；用腕部近景 + 接触信号兜底。

### 3.5 VFS：无力/触觉 API 下的准接触观测

**定位**：不是力估计，不输出牛顿；只输出 contact / slip / insertion-depth 的概率/序数，用于门控与闭环。

**输入**（滑窗 10–20 帧）：

```text
q_t, q_{t-1}, a_{t-1}        # 关节/动作
x_t, x_{t-1}                 # EE 位姿
g_t, g_cmd                   # 夹爪开度/命令
I^{wrist}_t, I^{wrist}_{t-1} # 腕部图像
I^{high}_t                   # 高位图像（可选）
phase_t                      # SSG 相位
```

**三路特征**：

1. **本体 surprise**：
   - 训练一个轻量动力学预测器 `D_prop(q_t, a_t, g_t) → q_{t+1}`（或 EE 增量）；
   - 残差 `r_p = ||q_{t+1} - D_prop(...)||`；
   - 自由空间残差小；接触/阻塞时残差大；用每机器人自由空间基线归一化。
2. **视觉流 surprise**：
   - 用确定性光流（Farneback）或同 checkpoint 的 flow head，计算腕部图像流；
   - 用 EE 运动 + 单目相对深度预测“若无接触的流”；
   - 残差 `r_v`：预测流与观测流的差异；夹爪动了但物体没动 → 滑移/阻挡。
3. **夹爪 stall**：
   - `r_g = |g_t - g_cmd|` 或夹爪开度在命令闭合后仍不收敛；
   - 对夹取/拉链/插头有效。

**融合**：

```text
contact_logit = MLP([r_p, r_v, r_g, phase, g_t, |x_t-x_{t-1}|])
slip_logit    = MLP([r_p, r_v, g_t, object_flow - gripper_flow])
depth_hat     = MLP([r_v, wrist_patch, phase])   # 序数/相对深度
```

- 输出 contact/slip 概率 + insertion depth（相对/序数）+ 置信度。
- 训练：自监督下一帧预测（全数据）+ 弱标签（规则：夹爪闭合、物体运动 onset、插入段、滑移段）+ 10% 人工抽检。
- 校准：每机器人前 1–2s 自由空间运动估基线；温度缩放/分位数校准。
- 使用：
  - `contact>τ_c` 且 `depth<target` → 慢速/小步搜索/微摆；
  - `slip>τ_s` → 夹紧/重抓；
  - `contact` 丢失且 `depth` 未达 → 回退/重对准；
  - 闭合 stall → 调整姿态/位置。
- **不声称**：不估计力的大小；不做力控；不做大力挤压。只做位置限制下的小步搜索。
- **证据**：VT-WAM 证明触觉对接触密集任务有用（71.67% vs Fast-WAM +26.67pp），但我们没有触觉；NeuralActuator 证明无 F/T 外力估计可行，但需要执行器遥测，我们也没有。因此只能用“位置/视觉/夹爪”的替代信号。这是本报告的诚实边界。

### 3.6 PGL/OPT：从 2D 锚点到 3D 接触目标

保留第 7 轮三级目标（槽位 → 2D 锚点 → 6D 位姿），但升级：

- **PGL**：用 MSF-3D 的容器/目标 slot 生成 3D 目标；2D 锚点只作为可视化/训练同分布 overlay；不再依赖推理期外部 SAM。
- **OPT**：`H_i = (T_B^R)^{-1} · T_B^G(t_rel)`；K 条行为对齐演示的稳健统计；新增**接触感知释放参数**：释放高度、释放速度、插入前预接触偏移、闭合方向。
- **决策**：σ 小 → 直接执行；σ 中 → 腕部伺服；σ 大 → 退化到锚点伺服；τ_task 从演示分布估。
- **接触目标**：T10/T26 的插入轴、T19/T31 的拉链方向、T27 的堆叠轴，作为 3D slot 的属性；VFS 的 contact/depth 用于判断“到没到”。
- **风险**：透明/布料/小件容器位姿不稳；分桶回退；T07/T13 可争议任务不强行用 OPT。

### 3.7 ICR：几何/运动键，不用独立编码器

第 7 轮的 ICR 用“缓存上下文编码”；本轮为单模型审计改成：

- **键**：任务/步骤复述（同 checkpoint 文本编码）、相位、目标-容器相对位姿、EE 速度/光流统计、夹爪状态；**不取全局外观**。
- **值**：K 段动作先验（稳健均值）+ 相对位姿统计；编码缓存只用同 checkpoint 的视觉/文本编码，不训练第二个 encoder。
- **注入**：上下文 token 拼接 + 动作先验小权重融合；训练时同步注入，避免推理期首次见 token。
- **延迟**：HNSW <5ms；K=1–4；p99 超窗降 K/降维。
- **风险**：透明/拉链任务键不稳；回退到相位先验；检索库是数据，模型卡披露。

### 3.8 SVL-v2：contact-aware 收尾

```python
def svl_v2(step, obs, plan, budget=2):
    for attempt in range(budget + 1):
        target = PGL.render(plan, obs)          # 3D/2D 目标
        ctx = ICR.retrieve(step, obs, k=4)
        for chunk in stream(policy.act(obs, target, ctx, phase=step)):
            send(chunk)
            c, s, d = VFS.update(obs)
            if c > TAU_C and d < TARGET_D:
                slow_mode(); nudge_search()     # 接触但未到位
            if s > TAU_S:
                regrasp(); break
            if predicate_met(step, obs) and c > TAU_C:
                break
        if not predicate_met(step, obs):
            plan = revise(plan, obs, diagnose(step, obs)); continue
        open_gripper(slow=True); sleep(0.4)
        if stable(step, obs, window=0.4):
            return True
        if repairable(step, obs):
            plan = nudge_plan(step, obs)
        else:
            regrasp(step)
    return False
```

- `slow_mode`：降低步长/速度，限制最大位移，避免大力挤压。
- `nudge_search`：沿插入轴/闭合方向做小步搜索（±几毫米/几度），用 contact 信号找“进入”的瞬间。
- `stable`：物体/容器相对位姿在 0.4s 内变化 <ε；谓词保持。
- 预算：普通任务 ≤2 次；长程任务（T16/T17/T31）≤1 次；Endurance Governor 兜底 180s。
- 风险：接触信号误判导致反复搜索；双阈值 + 置信度 + 总时长守卫。

### 3.9 DTI：云端单 checkpoint 的快/慢双路

**约束**：API 是请求-响应，执行完 chunk 才调用下一次；没有连续观测流。因此“异步”只能是服务器侧预计算。

- **慢路**：完整 VLA + action expert，出 T_a 步 chunk；自由空间/远距离。
- **快路**：同 checkpoint 前 N 层 + 轻量 action head；接触/插入/闭合时以更低延迟出小修正；训练时从慢路蒸馏。
- **VLASH 式预计算**：机器人执行 chunk k 时，用 chunk k 的动作把状态向前滚，预计算候选 chunk k+1；下一次真实观测到达时用 RTC 式 inpainting/拼接校正。
- **RTC**：把新 chunk 与旧 chunk 重叠部分做 inpainting/加权，避免拼接抖动。
- **VLA-RAIL 式平滑**：对 chunk 内/间做多项式平滑/速度缩放；减少接触阶段的抖动。
- **选择**：SSG 相位 + VFS contact 决定快/慢路与 T_a；T_a 是提交元数据，先测 p99 再定 8 或 16。
- **证据**：CloudEdgeVLA 在 40-step 延迟下仍保持 63.8–78.0%，VLASH/单路径的退化分别 ≤6.4%/≤3.0%；VLASH 最高 2.03× 加速、17.4× 反应延迟降低；RTC 无需训练改动；VLA-RAIL 把 5–10Hz 推理与 200–1000Hz 控制解耦。
- **风险**：预计算用预测状态，接触突变时可能错；下一次观测必须校正；p99 超窗关快路。

### 3.10 TTC-SV：同 checkpoint 自验证，不引入第二模型

- **采样**：flow matching 采样 K 个候选 chunk（K=1 自由空间，2–4 接触）。
- **打分**：同一 checkpoint 的 value/progress/contact 头；输入候选动作 + 当前 MSF/VFS token；输出成功概率/进度/接触合理性。
- **选择**：`score = α·value + β·progress + γ·contact_consistency - δ·jerk`；若 top-2 margin 小，取均值/保守候选。
- **训练**：用演示成功/失败/进度标签 + 自监督 TD/回报；DiVeR 式决策关键重加权（采样动作离散度高的状态权重大）。
- **异步**：K 个候选并行采样；延迟不够时 K=2 或用快路打分。
- **证据**：RoboMonkey/DiVeR 类测试时扩展在 OOD 上显著；但那些工作常用独立 verifier，我们受单模型限制，只能用同 checkpoint 头。**这是妥协，必须消融验证**。
- **风险**：value 头校准差/OOD；只在 margin 足够时重排；否则执行均值；若审计不允许，退回无 TTC。

### 3.11 AXIS-HW：轴感知 + 每机器人指纹

- **轴推断**：从观测统计（背景颜色/纹理、物体位置分布、未见物体嵌入距离、人手出现） + SSG 进度，输出 5 轴概率；一个小 head，同 checkpoint。
- **调制**：
  - 位置轴 → 更多依赖 MSF/OPT；
  - 干扰物 → 更多腕部/接触；
  - 背景 → 几何/运动键，降外观键权重；
  - 未见物体 → 提高 TTC K/保守阈值；
  - 人为干扰 → 更慢、更频繁谓词校验、NRB 恢复。
- **机器人指纹**：前 1–2s 自由空间运动估关节零位/偏置/跟踪基线；用 AdaLN context token 调制策略；确定性动作校正。Self-Adaptive VLA 在执行器偏置/编码器偏移下恢复 >80%。
- **单模型**：轴 head/context head 在同一 checkpoint；不做每轴专家。
- **验证**：调试槽若只能接触一台机器人，硬件轴无法直接验证；用模拟偏移（±0.01 rad 零位、±5% 增益、相机 jitter）做离线鲁棒性；若真实 N 台可测，优先。
- **风险**：硬件轴可能被评测随机化但影响不大；若消融无增益，砍掉。

### 3.12 WM-D：训练期世界模型蒸馏（可选）

- 用冻结世界模型（如 UnifoLM-WMA-0 或 DreamZero 特征）在官方帧上缓存特征；VLA 视觉路径加特征对齐损失；teacher 不加载到推理。
- 证据：Think Like WM 的 0.8B 学生 LIBERO 97.9%、RoboCasa-GR1 48.2→50.5%、部署 32ms/1.86GB，且与基线部署完全一致。
- 作用：补“未见物理运动”的泛化；与接触/多视角互补。
- 资源：缓存 33k episodes 特征；8×H100 数天；存储；只在 E7 做一次。
- 风险：teacher 域不匹配/特征对齐伤害；若离线无增益，砍掉。

### 3.13 NRB：官方备注恢复 + 接触失败恢复

保留第 7 轮 NRB（官方 human 备注 → 破坏/恢复对），新增接触失败：

| 任务 | 官方备注（例） | 场景化 | 恢复 |

| T27 | 叠了第二个之后拿下第二个 | 移除 bowl2 | 重放 bowl2 → 继续 |
| T19 | 拉上拉链之后拉开 | 拉开 | 重新拉合 |

### 3.15 推理伪代码

```python
def get_action(obs, state):
    task, phase = SSG.match(obs.language, state.step)
    msf = MSF3D.encode(obs.images, obs.proprio, phase)
    vfs = VFS.update(obs.proprio, obs.images.wrist, state.history, phase)
    target = PGL.target(msf, phase)
    ctx = ICR.retrieve(task, phase, msf, vfs, k=4)

    if phase in CONTACT_PHASES or vfs.contact > TAU_C:
        exit = "fast"; K = 2
    else:
        exit = "slow"; K = 1

    cands = policy.sample(obs, msf, vfs, target, ctx, K=K, exit=exit)
    best = TTC.select(cands, msf, vfs, phase)
    actions = RTC.stitch(state.prev_chunk, best)
    state.prev_chunk = actions
    state.history.append(obs)
    return actions, meta.token
```

```python
def vfs_update(proprio, wrist_img, history, phase):
    r_p = norm(proprio.q_next - D_prop(proprio.q, proprio.a))
    r_v = norm(flow(wrist_img) - flow_pred(proprio.dx, wrist_img))
    r_g = abs(proprio.g - proprio.g_cmd)
    c = sigmoid(MLP([r_p, r_v, r_g, phase, proprio.g]))
    s = sigmoid(MLP([r_p, r_v, object_flow - gripper_flow]))
    d = MLP([r_v, wrist_patch, phase])
    return calibrate(c, s, d)
```

## 4. 数据引擎

### 4.1 数据政策

- **只用官方 33k**（+ 确定性增强）；外部数据默认 OFF，规则未明前不并入训练。
- **任务平衡**：ManipArena 显示 200/task 平衡可优于 ~500/task；UniBot 每任务约 1k，训练时用温度采样/每任务上限，避免简单任务主导。
- **来源分层**：官方数据按任务/难度/场景分层；held-out 按轴切分，不用随机帧切分（避免泄漏）。
- **不合成接触物理**：布料/拉链/透明/插拔的接触合成不可靠；只做 2.5D 编辑/背景/位置/干扰物增强；仿真是分析工具，不是主数据源。

### 4.2 接触/滑移/插入标签

- 每任务抽 300 episodes（约 9.6k）做弱标签；规则：
  - gripper close → contact with object；
  - object motion onset after close → grasp；
  - EE near container + object stops → placement/insertion contact；
  - object motion relative to gripper while closed → slip；
  - insertion segment → depth from object/container keypoints/relative pose；
  - closure/zip → step completion + visual change。
- 自监督：下一帧本体/视觉预测；自由空间 vs 接触段的对比学习。
- 人工：10% 抽检；接触/滑移二值一致性目标 >90%；冲突样本降权/丢弃。
- 难任务（T16/T19/T23/T31 布料/拉链）标签置信度低；只用相位 + 视觉变化，不强推接触深度。

### 4.3 几何/位姿标签

- 离线标定：用 `state_d435` + 机器人几何 + 演示中的 EE 位姿，估相机外参/桌面平面；重投影 <5px、桌面 <5mm 才入库。
- 容器/目标位姿：用演示的 EE/物体相对位姿 + 关键点 PnP/多视角三角化；抽检 10%，误差 <1cm 才入库。
- MVUCF 训练期辅助：深度查询/跨视角对应不需要人工深度标签；用多视角自监督。
- 不在推理期跑 FoundationPose/SAM/DepthAnything；所有几何能力进 checkpoint 或确定性代码。

### 4.4 轴/硬件标签

- 五轴：官方 `generalization` 备注（human_1/human_4/unseen_object_3）+ 增强模拟；备注编号含义未核实，按“条件类型”使用，不按编号硬映射。
- 硬件：官方数据没有多机器人指纹；训练时模拟关节零位偏移（±0.01 rad）、增益偏差（±5%）、相机 jitter/曝光、网络延迟（0–200ms）；用 AXIS-HW 的 context token 学习补偿。
- 验证：调试槽若可接触多台机器人，优先做硬件轴 A/B；否则只做离线鲁棒性，不宣称真机硬件泛化。

### 4.5 增强

- 背景替换（官方背景 + 程序纹理）、物体位置平移/旋转、干扰物插入、视角 dropout、光度/模糊/噪声、遮挡、延迟/丢帧。
- 接触段增强要保守：不要改变插入轴/闭合方向的几何；不要合成不存在的接触力。
- 增强只用于训练，不改变官方评测分布；验证集用真实 held-out。

### 4.6 合成预算（砍）

- 不做全 32 任务高保真孪生；不做运行时仿真/MPC；不做仿真 RL；不做布料/拉链/透明全物理；不把 WMA-0 放主路径。
- 只保留 2.5D 编辑 + NRB 破坏/恢复 + 少量刚体合成（放置/堆叠）用于消融；合成不超过真实数据的 20%。

### 4.7 QA 与来源

- 自动 QA：四路同步、时长、动作平滑/加加速度、夹爪事件、步骤覆盖、5 复述匹配。
- 人工抽检 10%；单批拒绝率 >20% 停采。
- 来源记录：数据集/任务/帧/标签/增强/许可；模型卡附数据清单。
- 外部数据/L2L：默认 OFF；邮件 `challenge_support@unitree.com` 确认后开；比赛期间不开源核心权重/检索库。

## 6. 部署与云端协同

### 6.1 API 约束

- 请求-响应：平台执行完 chunk 才调用下一次 `get_action`；没有连续观测流。
- chunk 固定（`action_chunk_size`）；joint/ee 互斥；N 个连续端口；token 双处校验；`reset()` 每 episode。
- 观测只给 API 目录中的键；没有 F/T/电流/深度/标定。
- 评测机器人随机顺序；每端口独立 episode；共享后端必须状态隔离。

### 6.2 延迟预算

| 项 | 估计 |
|---|---:|
| 网络/观测传输 | 30–80ms |
| 视觉编码 + 融合 | 40–100ms |
| VLM + action expert | 100–250ms |
| 辅助头（VFS/TTC） | 5–20ms |
| 合计（慢路） | 175–450ms |
| chunk=8 @30Hz | 267ms |
| chunk=16 @30Hz | 533ms |
| 快路目标 | 50–120ms |

策略：先测 p99；若 chunk=8 超窗，改 16 或启用快路；接触阶段优先快路，自由空间慢路。TTC K=4 只在预算内开；否则 K=2/1。

### 6.3 异步预计算

```text
t0: 收到 obs_t → 返回 chunk k
t1: 机器人执行 chunk k；服务器用 chunk k 滚状态，预计算候选 chunk k+1
t2: 收到 obs_{t+1} → 用真实观测校正/选择 chunk k+1（RTC 拼接）
```

- 这能隐藏一个 chunk 的等待；不能消除预测误差。
- 接触突变时，预测状态可能错；下一次观测必须校正；VFS 置信度低时降权预计算。
- 不在机器人端跑模型；所有计算在云端。

### 6.4 多端口服务

- 方案 A：每端口独立进程/模型副本，最稳，显存 N 倍。
- 方案 B：共享权重 + 每端口 KV/状态 + 批处理；省显存，但 p99 受并发影响。
- 推荐：共享权重 + 每端口 session；接触阶段请求优先级；健康检查/超时/降级；N 端口从 8765 连续。
- 监控：每端口延迟、失败率、reset 次数、token 错误、GPU 显存/温度。

### 6.5 安全与回退

- 位置限制 + 最大步长 + 关节限位；不做力控/大力挤压。
- 接触慢速模式；滑移重抓；插入失败回退；总时长守卫 180s。
- 服务器过载：降 TTC K、关快路、回退慢路/单候选；模型崩溃：返回保守保持/撤回动作？API 没有显式安全动作；必须在服务端保证可用性。
- 人工干扰：更频繁谓词校验、NRB 恢复、降低速度。

### 8.3 新核心展开

**I14 MSF-3D（P0）**
- 动机：4 路相机不是“更多视角”，而是“接触段的几何”；静态拼接会被腕部主导/背景干扰。
- 差异：训练期 MVUCF 式几何注入，部署不跑深度/标定模型；阶段路由用 SSG 相位做强先验，而不是纯学习。
- 可行性：视频 backbone 已支持多图；几何辅助只加训练损失；部署零额外 FLOPs。
- 资源：8×H100 3 周；无需外部标注（多视角自监督 + 演示位姿）。
- 步骤：多视角编码→深度/对应辅助→阶段路由→3D token→PGL/OPT 接线。
- 风险：API 无标定；透明/反光/小件；用腕部/单目回退，位姿误差 >1cm 退出 OPT。

**I15 VFS（P0）**
- 动机：API 没有 F/T/电流/触觉；接触必须从位置/视觉/夹爪推断。
- 差异：不是力回归，是 contact/slip/insertion 的概率观测；本体动力学 surprise + 视觉流残差 + 夹爪 stall 三路互补；每机器人基线校准。
- 可行性：官方数据可自监督下一帧预测；规则弱标签 + 10% 人工；小 head，推理 <10ms。
- 资源：9.6k episodes 弱标签；2 周；无需力传感器。
- 步骤：特征→预测器→弱标签→校准→门控→与 SVL 接线。
- 风险：跟踪残差被控制器刚度/摩擦/延迟污染；contact F1 <0.6 关；不做力控。

**I16 DTI（P1）**
- 动机：云端是唯一算力；chunk=8 只有 267ms；TTC/多视角会吃预算。
- 差异：单 checkpoint 快/慢 exit；同权重；VLASH 预计算 + RTC 拼接；不做机器人端 edge 模型。
- 可行性：现有 VLA 可加 early-exit/轻量 head；服务端可做 session/批处理。
- 资源：8×H100 2 周；服务端 1 人。
- 步骤：快路蒸馏→预计算→拼接→压测→相位调度。
- 风险：预计算用预测状态，接触突变会错；p99 超窗降 K/关快路。

**I17 TTC-SV（P1）**
- 动机：接触段一个错误 chunk 就毁掉终局；测试时扩展能提 OOD。
- 差异：不引入第二 verifier；用同 checkpoint value/progress/contact 头；DiVeR 式决策关键重加权；只在 margin 足够时重排。
- 可行性：flow matching 可采样 K 个；value 头可训练；K=2 延迟可控。
- 资源：采样算力；2 周；离线标签。
- 步骤：value 标签→训练→margin 校准→消融→与 SVL 接线。
- 风险：value 头 OOD/校准差；审计；K=4 超窗。

**I18 AXIS-HW（P2）**
- 动机：N 台机器人；硬件偏移是隐藏轴；Self-Adaptive >80%。
- 差异：轴感知调制 + 每机器人指纹；不做每轴专家；无测试时梯度。
- 可行性：前 1–2s 自由空间估基线；AdaLN context token；模拟偏移训练。
- 资源：调试槽/模拟；2 周。
- 步骤：轴 head→指纹→调制→消融。
- 风险：硬件轴可能影响不大；无多机器人调试则只做离线，不宣称。

**I19 WM-D（P2）**
- 动机：世界模型补物理泛化；运行时太重。
- 差异：只蒸馏特征，部署丢弃 teacher；与接触/多视角互补。
- 可行性：Think Like WM 证据；缓存特征；单次训练。
- 资源：8×H100 3–5 天；存储。
- 步骤：选 teacher→缓存→对齐→消融。
- 风险：域不匹配/伤害；无增益砍。

**I20 接触数据协议（P1）**
- 动机：VFS/SVL 需要接触/滑移/插入标签；官方数据没有。
- 差异：规则弱标签 + 自监督 + 10% 人工；按任务平衡；来源/许可记录。
- 可行性：9.6k episodes；1 周；CPU/GPU 混合。
- 步骤：规则→抽检→QA→版本化。
- 风险：布料/拉链标签噪声；只用相位/视觉变化兜底。

### 8.4 已砍清单（跨轮）

| 砍掉 | 原因 |
|---|---|
| 每任务 LoRA/模型合并 | 单模型审计；32 任务碎片化；OOD 收益存疑 |
| 全 32 任务高保真孪生 | 成本高；接触物理 sim-to-real 差距大 |
| 运行时仿真/MPC | 延迟/标定/接触参数不可得 |
| 仿真 RL | 接触/布料/透明不可靠；真机数据更直接 |
| 布料/拉链/透明全物理 | 当前不可行；只做 2.5D/相位 |
| WMA-0 进主路径 | 运行时太重；只做训练期 teacher |
| 推理期外部 SAM/深度/检测 | 单模型审计；延迟；用 checkpoint 头/确定性几何替代 |
| 第二 verifier 模型 | 单模型规则；用同 checkpoint value 头 |
| 每轴专家模型 | 单模型；用轴感知上下文 |
| 外部实验室数据默认开启 | 规则未明；默认 OFF |
| FLEET 作为研究轴 | 部署是前提，不是贡献；降为检查单 |
| 通用多视角拼接 | FocusVLA/MVUCF 证明不够；用阶段路由/几何 |
| 纯视觉接触 | VT-WAM 证明触觉有用；无触觉，必须加本体/夹爪 |
| 云边模型分层（机器人端跑模型） | API 不允许；改为云端快慢双路 |

## 9. 风险、合规与开放问题

### 9.1 风险表

| 风险 | 概率 | 影响 | 缓解 | 停止条件 |
|---|---|---|---|---|
| 接触信号太弱 | 高 | 高 | 本体+视觉+夹爪三路；基线校准；真机抽检 | contact F1 <0.6 → 关 VFS |
| 标定缺失/几何不稳 | 高 | 中 | 训练期几何注入；单目/腕部回退 | 位姿 >1cm → 退 OPT |
| 延迟超 chunk | 高 | 高 | 快路；chunk 16；VLASH 预计算；TTC K 自适应 | p99 超窗 → 降 K/关快路 |
| 单模型审计 | 中 | 高 | 单 checkpoint；无外部模型；模型卡披露 | 审计不过 → 砍 ICR 动作先验/TTC |
| value 头校准差 | 中 | 中 | margin 阈值；均值回退；DiVeR 重加权 | 消融无增益 → 关 TTC |
| 硬件轴影响小 | 中 | 低 | 模拟偏移；调试槽；消融 | 无增益 → 砍 AXIS-HW |
| 外部数据违规 | 低 | 高 | 默认 OFF；邮件确认 | 禁止 → L2L 赛后 |
| 占位榜误导 | 高 | 中 | 只当弱先验；真榜发布后重跑 | 真实数据推翻 → 回退 R7 |
| 统计噪声 | 高 | 中 | 320 trials；配对/bootstrap；+3pp 门 | CI 跨 0 → 不上线 |
| 接触分类错 | 中 | 中 | 16/20/24 敏感性；调试槽 | n<16 或 q<0.6 → 回退 |
| 安全/挤压 | 中 | 高 | 位置限制；小步；关节限位；总时长 | 异常 → 停接触模式 |

### 9.2 合规开关

```yaml
policy:
  single_checkpoint: true
  external_models_at_inference: false      # no SAM/depth/detector/verifier
  retrieval_library: data_only             # ICR is data, not a model
  world_model_teacher: training_only       # WM-D; not loaded at inference
  external_lab_data: false                 # default OFF; email confirm
  force_control: false                     # position-limited only
  contact_mode: slow_small_step            # no crushing
  ttc: same_checkpoint_value_head
  debug_slots_per_release: 1
  camera_calibration: offline_or_learned    # no runtime external calibration model
```

### 9.3 开放问题

1. API 是否真的没有隐藏的力矩/电流/触觉键？是否允许通过关节位置差分估计？
2. 相机内参/外参/基线是否公开？`state_d435` 的用途？双目是否同步？
3. N 台机器人的准确数量、型号差异、每端口并发/延迟上限？
4. 不计分调试槽的次数/成本/是否随机化五轴？能否指定机器人？
5. 外部数据/开源权重/预训练模型的规则？L2L 是否允许？
6. 步骤分的聚合公式（平均部分分？最好？）；成功率与步骤分的精确 tie-break。
7. `action_chunk_size` 是否可运行时变化？返回少于 T_a 是否合法？chunk 内能否中断？
8. 单模型定义边界：辅助头/检索库/确定性代码/世界模型 teacher 如何披露？
9. 语言指令是否只在 5 条复述中采样？是否中文/未见复述？
