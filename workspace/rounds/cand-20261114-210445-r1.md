# 第 1 轮（灵感循环第 1 轮；本轮灵感：「需求洞察」×「通用操作」；承接 MODGAUGE / LeanGauge 基线）

> 背景：LeanGauge 把「等待大数据」改造成「主动发现需求盲区 + 少样本局部校准」，但它默认操作是任务专用、上下文固定的。真实具身系统的价值恰恰来自「通用操作」——抓取、推、放置、插入、递送等可被跨任务、跨物体、跨本体复用的操作原语。通用性不是免费的：它通过**削弱前置条件、抽象化效应模型**换来更大的声明适用域，于是声明域的增长速度远快于被见证域。与此同时，「需求洞察」面对的对象其实是**操作组合**，而不是单个操作；系统能认证的供给是单算子契约，用户真正要的是「抓起来→绕过桌沿→轻放」这类组合。二者之间的缺口，不只是数据稀疏，而是**运输（transport）与组合（composition）**。
>
> 本轮核心命题：
>
> **把「通用操作」从一个「被复用的技能」，重新定义为「一个必须在上下文态射下可运输、在接口不变式下可组合、在需求加权下可取证」的计量契约对象。用需求驱动的组合覆盖，找出「声明通用、却从未被见证」的运输/组合盲区，并把它们送回 LeanGauge 的见证闭环就地补齐；补不齐就沿通用性阶梯严格退化。**
>
> 设计 **UNIGAUGE-RAS**（UNIversal operation metroloGY with GAUGE audits for RAS）：「通用操作计量」。IP-315~321；定义 416–430；实验 E419–E431。理论姿态：**UNIGAUGE 是 LeanGauge 的组合前置层**——不改变 MODGAUGE 五不变式与 LeanGauge 的见证闭环，只在「单算子已认证」与「组合可执行」之间增加运输证书与组合契约；当禁用通用库、每个算子只在其原始上下文使用时，严格退化为 LeanGauge。

## 0. 直觉与动机

**灵感 1（通用操作 → 通用性 = 声明域的膨胀 + 见证域的滞后）**
直觉：一个「通用抓取器」看起来比「抓杯子」更强，但它真正的变化不是能力变多，而是**它敢声明的场景变多**。为了让同一个算子适配杯子、瓶子、盒子，工程师会放宽前置条件（「任意可抓物体」）、抽象效应（「夹紧即稳定」）、忽略接口差异（「夹爪开度连续可调」）。每一步放宽都扩大声明域 `Dom_o`，却不一定扩大被计量见证的集合 `W_o`。于是通用操作的典型故障不是「不会做」，而是**在声明的通用域里，有一部分子域从未被任何样本覆盖，系统却按「通用」的默认确信去执行**。这就是「通用性间隙」。

**灵感 2（需求洞察 → 需求是组合的，而且需求对供给内生）**
直觉：用户不会说「请给我一个抓取原语」，而会说「把这只热水杯放到桌沿内侧但别太靠边」——这是一个**组合需求**：抓取∘运输∘放置∘净空约束∘力约束。LeanGauge 的覆盖矩阵在 (距离×材质×互扰) 上打洞，却默认「洞里的算子是给定的」。更重要的是，**需求会被现有库诱导**：如果系统只提供「通用抓取」，用户会把需求也表述成「抓一下再说」，那些「其实需要双手协同/需要先推开障碍」的真实需求就被压成了不合适的模板。因此需求洞察必须是**供给无关的**：从任务结果残差与失败回溯里估计需求 `D*`，而不是从「用户点了哪个已有操作」里统计需求 `D_obs`。否则系统会精确地认证一个错误的操作库。

**灵感 3（通用操作 → 运输与组合是两种不同的失效面）**
直觉：通用性有两种看似相似、实则不同的检验。
- **运输失效（transport）**：同一个算子在上下文 A 认证过，搬到上下文 B（不同本体、不同摩擦、不同坐标系）后，效应模型发生漂移，契约不再成立。这需要「上下文态射」与「运输残差」。
- **组合失效（composition）**：两个各自认证的算子拼起来，接口处出现未建模的耦合（抓取后放置时的滑移、推与抓的时序干扰），风险预算不再可加。这需要「接口不变式」与「耦合上界」。

把两者混为一谈，就会出现最危险的情形：**每个模块都合规、每条单算子契约都有效，但组合整体越界**。这正是 R73「自信地组合一个错误世界」在「通用操作库」上的版本。

## 1. 形式化定义（增量：定义 416–430）

**定义 416（通用操作原语 GOP）** 通用操作原语
`o = (I_o, pre_o, post_o, Eff_o, EC_o, Dom_o, κ_o)`：
- `I_o`：类型化接口（物体、位姿、力、开度等端口）；
- `pre_o / post_o`：前置 / 后置谓词；
- `Eff_o`：效应模型（动作 → 状态变化）；
- `EC_o`：MODGAUGE 计量契约（不确定度预算与见证义务）；
- `Dom_o ⊆ ∏_j C_j`：**声明的**通用上下文域（物体类别 × 位姿 × 摩擦 × 本体 × 环境）；
- `κ_o ≥ 0`：该算子对接口耦合的固有敏感系数。
`W_o ⊆ Dom_o` 为实际见证集。称 `Dom_o \ W_o` 为**通用性间隙**。

**定义 417（上下文态射与可运输性）** 上下文态射 `μ: I_o → I_c` 是接口类型、参数与单位的一个映射（含本体标定、坐标系变换、尺度归一）。`μ` 称为**契约保持的**，若
`pre_o` 的原像满足 `μ(pre_o) ⇒ pre_c`，且 `Eff_c ∘ μ ≈ μ ∘ Eff_o`（在见证尺度上）。

**定义 418（运输证书 TC）** 算子 `o` 沿 `μ` 运输到上下文 `c` 的证书
`TC(o, μ, c) = (r_μ, δ_μ, EC_c)`：
- `r_μ = sup_{x ∈ W_o} ‖Eff_c(μ(x)) − μ(Eff_o(x))‖ / scale(x)`：运输残差；
- `δ_μ`：运输覆盖概率；
- `EC_c = μ_* EC_o`：契约的前推。
`TC` 有效 ⇔ `r_μ ≤ ε_t` 且 `EC_c` 被 `EC_o` 在见证域上支配。运输只对 `W_o` 有保证；`Dom_o \ W_o` 上的运输**没有**保证。

**定义 419（操作组合与接口不变式）** 组合
`q = o_1 ; o_2 ; … ; o_n`
有定义 ⇔ 相邻接口类型匹配且 `post_{o_i} ⇒ pre_{o_{i+1}}`。称接口不变式 `Inv(q)` 成立，若在接口处不存在改变后续算子前提的未建模副作用。组合的**耦合项** `κ(q)` 是接口处未建模交互的风险上界（滑移、时序竞争、力传递）。

**定义 420（组合契约与契约泄漏）** 组合契约
`EC_q = ⊕_{i} EC_{o_i} ⊞ κ(q)·Λ`
其中 `⊕` 为风险预算的保守合并，`Λ` 为接口敏感度的尺度矩阵。若 `κ(q) ≤ κ_max`，称组合**次可加**，`EC_q` 可直接由分量得到；否则称存在**契约泄漏** `L(q) = κ(q) − κ_max > 0`，此时**不得**仅凭分量证书认证组合，必须补充接口见证。关键点：单算子认证 `∧_i Cert(o_i)` **不蕴含** `Cert(q)`。

**定义 421（需求—组合覆盖矩阵）** 在组合模板 `q`（算子序列 × 物体类别 × 上下文类）上的覆盖矩阵
`M_op[q] = (n_demand, n_transport, n_compose, gap_sym, r_μ^max, κ_res, cost_risk)`：
- `n_demand`：需求计数；`n_transport`：运输见证次数；`n_compose`：组合见证次数；
- `gap_sym`：声明域与被见证域的对称差测度；
- `r_μ^max`：已观测最大运输残差；`κ_res`：已观测耦合残差；
- `cost_risk`：该组合的风险等价类。

**定义 422（通用操作盲区）** 组合模板 `q` 为通用操作盲区 ⇔
`n_demand ≥ τ_d ∧ cost_risk ≥ τ_c ∧ ( n_transport ≤ τ_t ∨ n_compose ≤ τ_n ∨ r_μ^max > ε_t ∨ κ_res > κ_max )`。
它是 LeanGauge 定义 399 在**组合坐标**上的扩展：不仅「没采过样」，还包括「采过样但没运输过」「运输过但没组合过」「组合过但接口耦合未见证」。

**定义 423（需求内生性与供给无关需求）** 观测需求
`D_obs(q) = P(q | 库 ℒ)` 是给定当前操作库 ℒ 时的需求，受**供给诱导**。供给无关需求 `D*(q)` 由任务结果残差与失败回溯估计：
`D*(q) ≈ E[ r_task | q 可由任意操作实现 ]`。
约定：盲区判定与取证排序只允许使用 `D*`；用 `D_obs` 会系统性低估「库外需求」（见引理 57）。

**定义 424（通用性证书 GC_op）** 对算子/组合 `x` 与目标域 `D_req ⊆ Dom_x`，通用性证书
`GC_op(x) = (W_x, δ, r_μ^max, κ_res, L_res)`，有效 ⇔
1. `D_req ⊆ W_x`（以至少 `1−δ` 覆盖）；
2. `r_μ^max ≤ ε_t` 且 `κ_res ≤ κ_max`；
3. 若无组合见证，则 `x` 只被认证为单算子，**不得**进入组合执行路径。

**定义 425（需求加权取证排序）** 对盲区 `q` 的候选探针 `p`（定位到单算子 / 接口 / 上下文 / 组合四类之一），
`priority(p) = D*(q) · cost_risk(q) / cost(p)`。
选 `p* = argmax priority(p)`，若 `priority(p*) < τ_pri` 则转澄清或退化。取证样本只喂给 LeanGauge 的 I-Box 与 BP-Cal，更新 `W_x, EC_x`。

**定义 426（通用操作时序契约 UTC）** `UTC = (T_uni, B_uni, τ_pri, recovery)`：`T_uni` 为通用层单次取证时延上限，`B_uni` 为运输/组合取证总预算，`recovery` 为超时或预算耗尽的退化条件。UNIGAUGE 只在事件触发域运行，不侵入 MODGAUGE 的硬实时主循环。

**定义 427（通用性退化阶梯）** 失效时按序单调收缩可执行集合：
完整通用组合（运输 ∧ 组合证书有效）→ **专用算子**（只在原始 `W_o` 上下文使用，不回退声明域）→ **单步原语**（拆掉组合，只执行一个已认证算子）→ 第 0 层物理包络 / 遥操作 / 停机。每一级只能减小可执行集合。

**定义 428（UNIGAUGE 总览）** `UNIGAUGE = (MODGAUGE, LeanGauge, OPL, MORPH-CHECK, COMP-CERT, DC-Box, UNI-PROBE, GEN-DEG)`。禁用通用库（每个算子绑定单一上下文）时，`MORPH-CHECK` 退化为恒等，`COMP-CERT` 退化为逐算子校验，`DC-Box` 退化为 LeanGauge 的 D-Box，故 UNIGAUGE 严格退化为 LeanGauge。

**定义 429（联合安全主张）** 一次组合执行在 `(α, δ)` 下安全，若
`P(∃t: 违反 EC_q) ≤ Σ_i α_i + δ + n·ε_t`，
前提是：每个分量 `TC` 有效、`Inv(q)` 成立、`κ(q) ≤ κ_max`、且 `D_req ⊆ W_x`。前提任一失效，右端界失效（见 §6）。

**定义 430（通用性幻觉）** 系统处于通用性幻觉，若
`M_op` 在**已供给**的组合空间上全部被覆盖，但存在 `q` 使 `D*(q) > τ_d` 且 `q` 不在供给空间内。此时所有证书都有效，却没有任何证书针对真实需求。它是定义 423 的直接推论，也是本轮最深的隐患。

## 2. 关键算法骨架

```python
# IP-315 OPL：通用操作库（带接口契约的 GOP）
class GeneralOperation:
    ports: InterfaceType
    pre: Predicate
    post: Predicate
    effect: EffectModel
    ec: MetrologyContract
    domain: DomainBox          # 声明的通用域 Dom_o
    kappa: float               # 固有耦合系数 κ_o

# IP-316 MORPH-CHECK：上下文态射运输证书
class TransportChecker:
    def transport(self, op, mu, ctx):
        r = self.residual(op.effect, mu, ctx)      # 只在 W_o 上估计 r_μ
        ec_c = self.pullback(op.ec, mu)
        if r > self.eps_t or not self.ec_dominates(ec_c, op.ec):
            return TransportCert.invalid(r)        # 声明域扩大但没有见证
        return TransportCert(r, ec_c)

# IP-317 COMP-CERT：组合契约闭合（拒绝把分量证书当组合证书）
class CompositionCertifier:
    def compose(self, q, interface_inv):
        if not self._interfaces_match(q) or not interface_inv:
            return None                            # 组合未定义
        kappa = self._coupling(q)                  # 接口处未建模交互上界
        if kappa > self.kappa_max:
            return CompositionCert.leakage(kappa)  # 契约泄漏：必须补接口见证
        ec = self._add_contracts([o.ec for o in q.ops], kappa)
        return CompositionCert(ec, kappa)

# IP-318 DC-Box：需求—组合盲区（只使用供给无关需求 D*）
class DemandCompositionBox:
    def detect(self, M_op, D_star):
        spots = []
        for q, cell in M_op.items():
            if (D_star[q] >= self.tau_d and cell.cost_risk >= self.tau_c
                and (cell.n_transport <= self.tau_t
                     or cell.n_compose <= self.tau_n
                     or cell.r_max > self.eps_t
                     or cell.kappa_res > self.kappa_max)):
                spots.append(q)
        return sorted(spots, key=lambda q: D_star[q] * M_op[q].cost_risk)

# IP-319 UNI-PROBE：需求加权取证，喂给 LeanGauge I-Box
class UniProber:
    def choose(self, q, budget):
        probes = self._decompose(q)               # 单算子 / 接口 / 上下文 / 组合
        scored = [(D_star[q] * self._risk(q) / max(c, 1e-9), p, c)
                  for p, c in probes]
        best = max((x for x in scored if x[2] <= budget), default=None)
        return best[1] if best and best[0] >= self.tau_pri else None

# IP-320 GEN-DEG：通用性退化（声明域回缩，而非缩小成功率）
class GeneralityDegrader:
    def fallback(self, q):
        if self._specialized_certified(q):  return "specialized"   # 回到 W_o
        if self._single_step_certified(q):  return "single_step"
        return "teleop"                                            # 第 0 层兜底

# IP-321 UNIGAUGE 主闭环
def UNIGAUGE_round(M, obs, task):
    qs = OPL.demand_compositions(task)
    D_star = DemandCompositionBox.supply_independent_demand(qs, M.outcome_log)
    spots = DemandCompositionBox.detect(M.M_op, D_star)
    for q in spots:
        tcs = [TransportChecker.transport(o, mu, M.ctx) for o, mu in q.bindings]
        cc  = CompositionCertifier.compose(q, M.interface_inv(q))
        if cc is None or cc.leakage or not all(tc.valid for tc in tcs):
            probe = UniProber.choose(q, M.B_uni)
            if probe is not None:
                LeanGauge.IBox.execute(probe)          # 只采见证样本
                LeanGauge.BPCal.calibrate(probe.samples)  # 只修契约
                continue
            return GeneralityDegrader.fallback(q)      # 超预算：严格退化
    return MODGAUGE_round(M, obs, qs,                    # 全部有效才进主循环
                          generality_cert=GC_op(qs, M.M_op))
```

## 3. 推导

**引理 52（通用性间隙不可由见证误差直接界定）** 设 `Eff_c` 在 `Dom_o \ W_o` 上相对于见证域无 Lipschitz / 运输先验，则任意仅基于 `W_o` 的经验风险，都存在一个在 `Dom_o \ W_o` 上与之一致、但在该区域违反 `EC` 的效应模型。故「声明通用」本身不提供任何超出 `W_o` 的保证；必须有定义 418 的运输残差或额外的域假设。系：`Dom_o` 的大小不能作为能力度量，只有 `|W_o|/|Dom_o|` 加运输界才有计量意义。

**引理 53（组合泄漏反例 / 分量证书不闭合）** 存在两个算子 `o_1, o_2`，各自 `EC` 有效，但 `o_1;o_2` 违反组合契约。构造：`o_1` = 抓取（合同假设夹持力恒定），`o_2` = 贴边放置（合同假设初始姿态扰动 ≤ ε_p）；单独认证时二者都被容忍，但 `o_1` 在搬运中引入的姿态扰动与 `o_2` 的贴边净空耦合，使 `κ(q) > κ_max`。因此 `Cert(o_1) ∧ Cert(o_2)` 推不出 `Cert(o_1;o_2)`，组合必须单独见证（定义 420）。

**引理 54（运输残差的保守传播）** 若 `Eff_c` 关于 `μ` 满足 `L`-Lipschitz、运输残差 `r_μ ≤ ε_t`，且 `EC_o` 在 `W_o` 上有效，则运输后的违反概率增量 `≤ L·ε_t`。证明：`‖Eff_c(μx) − μEff_o(x)‖ ≤ r_μ`，对 `EC` 的裕度取三角不等式，再对 `W_o` 的覆盖取并集界。系：运输不是免费泛化，`ε_t` 必须作为风险预算的加项进入 `EC_q`。

**定理 23（运输—组合端到端安全）** 若 (a) 每个分量 `TC` 有效且 `r_μ ≤ ε_t`；(b) `Inv(q)` 成立；(c) `κ(q) ≤ κ_max`；(d) 需求域以概率 `≥1−δ` 被 `W` 覆盖，则
`P(∃t: 违反 EC_q) ≤ Σ_i α_i + δ + n·ε_t`。
证明：对「运输失效、接口不变式失效、耦合超界、需求域漏出」四类事件取并集界；执行只使用运输与组合均有效的算子，故无额外未计量项。注意 (d) 是需求侧前提，不能用供给覆盖替代。

**引理 55（需求加权取证的样本复杂度）** 若供给无关需求 `D*` 在组合模板上把真实盲区排在前 `k` 的概率为 `p`，则达到同置信度所需见证数从 `n_min` 降为 `O(n_min / p_eff)`，`p_eff ≥ p/k`。当 `D*` 估计有偏时额外付出 `O(est_err / gap)` 的样本，且该偏差不能通过增加物理采样消除（只能通过更接近任务结果的失败回溯降低）。系：需求洞察降低平均成本，但不改变最坏情形下界。

**引理 56（严格退化）** 每个算子绑定单一上下文且禁用组合时，`MORPH-CHECK` 为恒等、`COMP-CERT` 退化为逐算子校验、`DC-Box` 退化为 LeanGauge 的 D-Box；UNIGAUGE 精确退化为 LeanGauge；再禁用需求层退化为 MODGAUGE。每级退化只减小可执行集合，安全侧单调不减。

**引理 57（需求内生性的系统性偏差）** 若需求只从当前库 `ℒ` 的调用统计 `D_obs` 估计，则对任意 `q ∉ ℒ` 有 `D_obs(q) = 0`，故 `D_obs` 永远无法发现「库外需求」；而 `D*` 由任务结果残差估计，对 `q ∉ ℒ` 仍可正。系：用 `D_obs` 驱动的取证会陷入「越用越只证已有操作」的自证循环，这正是定义 430 的通用性幻觉。

## 6. 本轮最大风险

**一句话**：UNIGAUGE 的全部安全界都建立在「真实需求 `D*` 可被任务结果残差识别、且通用算子的声明域可被运输 + 组合证书覆盖」这两个前提上；但通用性往往正是通过削弱前置条件换来的，而需求又会被现有操作库诱导成「库内可表达」的形式——于是系统可能在一片**完全有效**的证书上，精确地通用化了用户并不需要的操作组合，同时把真正的库外需求留在 `D_obs = 0` 的盲区里；这是「自信地组合错误世界」的通用操作版本，比 LeanGauge 的稀疏盲区更隐蔽，因为它没有失败样本，只有沉默的未需求。

**次级风险与缓解**：
1. **运输先验缺失** → 强制 `ε_t` 进入风险预算；无运输先验时退回专用算子（引理 52、54）。
2. **组合耦合不可估** → 接口见证优先；`κ > κ_max` 时禁止仅凭分量认证（引理 53）。
3. **需求内生性** → 只用 `D*` 排序；定期做「库外任务审计」；`D_obs` 仅作监控（引理 57）。
4. **通用性幻觉** → 定义 430 指标常态化监控；幻觉率超阈触发库扩展 / 主动澄清，而非继续认证。
5. **通用库膨胀导致组合爆炸** → 事件触发 + 组合模板剪枝；只对 `D*·cost_risk` 高的模板取证。
6. **退化被误当作能力** → 退化日志显式记录「声明域回缩」；禁止把专用成功率冒充通用成功率。
7. **实时性冲突** → UTC 超时即走专用算子或单步原语；通用层不阻塞硬实时主循环。

## 2. 形式化定义（要点）

**定义 416（通用操作原语）** `o=(I_o,pre_o,post_o,Eff_o,EC_o,Dom_o,κ_o)`；`Dom_o\W_o` 为通用性间隙。

**定义 417–418（上下文态射与运输证书）** `TC` 有效 ⇔ `r_μ≤ε_t` 且 `EC_c=μ_*EC_o` 被 `EC_o` 在 `W_o` 上支配。运输只对 `W_o` 有保证。

**定义 419–420（组合与契约泄漏）** `EC_q = ⊕_i EC_{o_i} ⊞ κ(q)·Λ`；`κ(q)>κ_max` 时存在泄漏 `L(q)`，**不得**仅凭分量证书认证组合。`Cert(o_1)∧Cert(o_2) ⇏ Cert(o_1;o_2)`。

**定义 421–423（需求—组合覆盖与盲区）** 盲区 ⇔ `n_demand≥τ_d ∧ cost_risk≥τ_c ∧ (n_transport≤τ_t ∨ n_compose≤τ_n ∨ r_μ^max>ε_t ∨ κ_res>κ_max)`。盲区判定与排序只允许使用供给无关需求 `D*`。

**定义 424（通用性证书 GC_op）** 有效 ⇔ `D_req⊆W`（≥1−δ）、`r_μ^max≤ε_t`、`κ_res≤κ_max`；无组合见证时只认证单算子。

**定义 425（需求加权取证）** `priority=D*·cost_risk/cost`；低于 `τ_pri` 转澄清/退化。

**定义 426–427（时序契约与通用性退化阶梯）** 通用组合 → 专用算子（回缩到 `W_o`）→ 单步原语 → 物理包络/遥操作/停机；每级只减小可执行集合。

**定义 428（总览）** `UNIGAUGE=(MODGAUGE,LeanGauge,OPL,MORPH-CHECK,COMP-CERT,DC-Box,UNI-PROBE,GEN-DEG)`；禁用通用库时退化为 LeanGauge。

**定义 429（联合安全主张）** `P(∃违反 EC_q) ≤ Σ_i α_i + δ + n·ε_t`，前提：分量 TC 有效、`Inv(q)` 成立、`κ(q)≤κ_max`、`D_req⊆W`。

**定义 430（通用性幻觉）** 供给空间全被覆盖，但存在库外 `q` 使 `D*(q)>τ_d`；此时证书全有效却没有一张针对真实需求。

## 3. 关键算法骨架

```python
# IP-315 OPL：带接口契约的通用操作原语
class GeneralOperation:
    ports; pre; post; effect; ec
    domain: DomainBox      # Dom_o
    kappa: float           # κ_o

# IP-316 MORPH-CHECK：运输证书（只在 W_o 上估计残差）
class TransportChecker:
    def transport(self, op, mu, ctx):
        r = self.residual(op.effect, mu, ctx)
        ec_c = self.pullback(op.ec, mu)
        if r > self.eps_t or not self.ec_dominates(ec_c, op.ec):
            return TransportCert.invalid(r)
        return TransportCert(r, ec_c)

# IP-317 COMP-CERT：组合闭合，拒绝分量证书冒充组合证书
class CompositionCertifier:
    def compose(self, q, interface_inv):
        if not self._interfaces_match(q) or not interface_inv:
            return None
        kappa = self._coupling(q)
        if kappa > self.kappa_max:
            return CompositionCert.leakage(kappa)
        return CompositionCert(self._add_contracts(q, kappa), kappa)

# IP-318 DC-Box：供给无关需求 D* + 组合盲区
class DemandCompositionBox:
    def detect(self, M_op, D_star):
        spots = [q for q, c in M_op.items()
                 if (D_star[q] >= self.tau_d and c.cost_risk >= self.tau_c
                     and (c.n_transport <= self.tau_t or c.n_compose <= self.tau_n
                          or c.r_max > self.eps_t or c.kappa_res > self.kappa_max))]
        return sorted(spots, key=lambda q: D_star[q] * M_op[q].cost_risk)

# IP-319 UNI-PROBE：需求加权取证，样本交给 LeanGauge I-Box/BP-Cal
class UniProber:
    def choose(self, q, budget):
        scored = [(D_star[q] * self._risk(q) / max(c, 1e-9), p, c)
                  for p, c in self._decompose(q)]
        best = max((x for x in scored if x[2] <= budget), default=None)
        return best[1] if best and best[0] >= self.tau_pri else None

# IP-320 GEN-DEG：通用性退化 = 声明域回缩
class GeneralityDegrader:
    def fallback(self, q):
        if self._specialized_certified(q): return "specialized"
        if self._single_step_certified(q): return "single_step"
        return "teleop"

# IP-321 UNIGAUGE 主闭环
def UNIGAUGE_round(M, obs, task):
    qs = OPL.demand_compositions(task)
    D_star = DemandCompositionBox.supply_independent_demand(qs, M.outcome_log)
    for q in DemandCompositionBox.detect(M.M_op, D_star):
        tcs = [TransportChecker.transport(o, mu, M.ctx) for o, mu in q.bindings]
        cc  = CompositionCertifier.compose(q, M.interface_inv(q))
        if cc is None or cc.leakage or not all(tc.valid for tc in tcs):
            probe = UniProber.choose(q, M.B_uni)
            if probe is not None:
                LeanGauge.IBox.execute(probe); LeanGauge.BPCal.calibrate(probe.samples)
                continue
            return GeneralityDegrader.fallback(q)
    return MODGAUGE_round(M, obs, qs, generality_cert=GC_op(qs, M.M_op))
```

## 4. 推导

**引理 52（通用性间隙）** 无运输 / Lipschitz 先验时，仅凭 `W_o` 的经验风险无法界定 `Dom_o\W_o`；「声明通用」本身不提供超出 `W_o` 的保证。

**引理 53（组合泄漏反例）** 存在各自 EC 有效的 `o_1,o_2`，使 `o_1;o_2` 因接口耦合 `κ(q)>κ_max` 而违反组合契约；故单算子认证不闭合组合。

**引理 54（运输残差传播）** 若 `Eff_c` 对 `μ` 满足 `L`-Lipschitz 且 `r_μ≤ε_t`，则运输后违反概率增量 `≤L·ε_t`；`ε_t` 必须进入风险预算。

**定理 23（运输—组合端到端安全）** 若 (a) 分量 TC 有效；(b) `Inv(q)`；(c) `κ(q)≤κ_max`；(d) 需求域以 `≥1−δ` 被覆盖，则 `P(∃违反 EC_q)≤Σα_i+δ+n·ε_t`。前提 (d) 不能用供给覆盖替代。

**引理 55（需求加权样本复杂度）** 真实盲区被 `D*` 排前 k 的概率为 p 时，见证数降为 `O(n_min/p_eff)`；先验无关时仅常数因子，最坏不优于 LeanGauge；`D*` 有偏时另付 `O(est_err/gap)`。

**引理 57（需求内生性）** 只用 `D_obs` 时对任意库外 `q` 有 `D_obs(q)=0`，永远发现不了库外需求；`D*` 由任务结果残差估计，对库外需求仍可正。

**引理 56（严格退化）** 单上下文 + 禁用组合时，MORPH-CHECK 为恒等、COMP-CERT 退化为逐算子校验、DC-Box 退化为 LeanGauge D-Box；UNIGAUGE 精确退化为 LeanGauge。

| E430 需求估计偏差 | D* 受失败回溯噪声污染 | 退化到均匀取证；安全界不失效 |
| E431 实时性 | 通用层额外开销 | 主循环抖动 <1ms |

## 7. 本轮最大风险

**一句话**：UNIGAUGE 的安全界依赖「真实需求 `D*` 可被任务结果残差识别、且通用算子声明域可被运输 + 组合证书覆盖」，但通用性往往正是靠削弱前置条件换来的，需求又会被现有库诱导成「库内可表达」——系统可能在一片完全有效的证书上，精确通用化了用户并不需要的组合，同时把真正的库外需求留在 `D_obs=0` 的盲区里；这是「自信地组合错误世界」的通用操作版本，比 LeanGauge 的稀疏盲区更隐蔽，因为它没有失败样本，只有沉默的未需求。
