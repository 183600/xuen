# 第 1 轮（新灵感循环第 1 轮；本轮灵感：「角色一致性」×「力控」）

> **基线**：v20（MetricVoiceGauge-NCD-HUTDH-v20 + IP-420–424）。本轮纪律：**角色是接触权限的语义锚点，力控是接触安全的物理边界**。不推倒 v20：PCA/CTS/CFC/HPC/CFCtrl 全部保留。本轮只做一件事：**把证书从“零碰撞”升级为“角色授权下的有界接触安全”**。

## 0. 直觉与动机

**灵感 1（角色一致性 → 证书的语义身份，而非运行期标签）**
直觉：v20 的证书回答“在参数 θ 下是否零碰撞”，但它默认所有接触都是事故。在接触密集的操作里，同一处接触对不同角色含义相反：夹爪**应该**碰杯子，搬运工**不应该**。若把“角色”当成可随时改写的运行期标签，证书就会在角色切换后被错误复用——夹爪的证书被拿去给“推手”用，接触权限越界却无人察觉。核心创新：**角色签名绑定器 (Role Signature Binder, RSB)**。角色不是名字，而是一份契约 `σ(r) = (A_r, Φ_r, C_r, T_r)`：授权接触区、力预算、控制器族、协作伙伴。证书绑定到 `σ(r)`，角色一致性定义为**证书签发时的角色 = 执行时的角色 ∧ 实际接触 ⊆ A_r ∧ 实际力 ∈ Φ_r**。关键反直觉点：**角色一致性不是让机器人“行为不变”，而是让证书的有效域与机器人被授权的接触域保持一致**——角色切换不是状态更新，而是**证书吊销事件**。

**灵感 2（力控 → 碰撞从二值禁止变为有界接触）**
直觉：经典碰撞证书把“接触”一律判为 UNSAFE；力控则把有意的、有界的接触当作任务本身。于是安全判据必须从“是否接触”变成“接触力是否在安全包络内”。核心创新：**力包络证书 (Force-Envelope Certificate, FEC)**。用保守摩擦锥 `‖f_t‖ ≤ μ_min f_n`、法向力区间、力矩上限、力变化率上限与物体力平衡裕度共同定义 `F_env(r,o)`；把 v20 的 CCV 窄相位从位置空间扩到**力轨迹空间**。关键反直觉点：**最危险的不是力太大，而是力方向滑出摩擦锥、或力变化率过大**——因此证书必须认证**整条力轨迹与阻抗行为**，而不是某一瞬时力值。

**灵感 3（两者统一 → 角色-力证书 Role-Force Certificate, RFC）**
直觉：角色回答“谁在何处、以多大预算接触”；力控回答“接触力如何随时间演化”。二者相乘才是完整的接触安全语义：**角色给出许可集，力控给出生效轨迹**。核心创新：**角色-力证书 (RFC)**，共享状态 `ζ_rf = (role_assignment, force_envelope, impedance_state, contact_mode, χ_role)`。统一接口：当 `χ_role = 1` 且力轨迹落在 `F_env` 内时，CCV 窄相位返回 `CONTACT_SAFE`；否则退回 v20 的零碰撞判定。关键反直觉点：**角色与力不是两个独立约束的叠加，而是同一个证书的两个坐标**——角色越具体，力包络可以越宽（活性越高）；角色越模糊，力包络自动收缩到零（退回零碰撞）。

**四者如何统一**
v21 = v20 之上的**语义-物理接触层**：RSB 是语义侧（角色→证书绑定），FEC 是物理侧（力→包络），ICC 是控制侧（阻抗增益→最坏力），RDM 是监控侧（角色漂移→吊销），CHC 是协作侧（交接→角色-力共识）。PCA/CTS/CFC/HPC/CFCtrl 继续回答“几何上哪里可去”，RFC 回答“接触上哪里可碰、以多大力碰”。

## 1. 研究问题（轮次升级版）

- **Q1（角色签名的可判定性）**：如何从任务图与感知中构造 `σ(r)`，使角色切换可被无歧义检测？角色一致性如何避免“标签一致但行为越权”？证书吊销后如何以最小活性损失回退到 v20？

- **Q2（力包络的保守构造）**：如何在摩擦系数、接触点、物体质量不确定下构造 `F_env` 且保证不偏大（漏判滑移）？有意接触与意外碰撞如何在力轨迹上区分？力变化率与阻抗瞬态如何纳入证书？

- **Q3（阻抗-力可证耦合）**：给定阻抗控制器 `(M,K,D)`，如何在有界扰动与建模误差下证明最坏接触力 `≤ f_max`？证书应约束增益、还是约束轨迹、还是两者并用？

- **Q4（多机器人角色交接）**：交接瞬间两个角色同时接触物体，如何保证角色共识与力包络连续？在角色漂移、通信延迟、力传感器偏差下如何维持 `Exec_v21 ⊆ Exec_v20`？

## 2. 设计原则（在 P31–P33 基础上新增 P34–P37）

**P34 角色-证书绑定律（Role-Certificate Binding）**
证书 C 仅在角色 `σ(r)` 下有效。角色签名 `σ(r) = (A_r, Φ_r, C_r, T_r)`，其中 `A_r` 为授权接触区、`Φ_r` 为力预算、`C_r` 为控制器族、`T_r` 为伙伴集。定义一致性指示
`χ_role(n,t) = 1 ⟺ r_n(t)=r_n^cert ∧ ContactSet(t) ⊆ A_{r_n} ∧ f_n(t) ∈ Φ_{r_n}`。
角色切换 ⇒ 证书吊销 ⇒ 强制回退 v20。**证书不能跨角色复用**。

**P35 力包络保守律（Force-Envelope Conservatism）**
`F_env(r,o) = { w=(f_n,f_t,τ) : 0 ≤ f_n ≤ f_max(r), ‖f_t‖ ≤ μ_min(o)·f_n, |τ| ≤ τ_max(r), ‖ḟ‖ ≤ R_max, wrench_balance_margin ≥ ε_w }`，
其中 `μ_min = max(0, μ̂ - k_μ·σ_μ)` 为摩擦系数置信下界。**力包络只能收缩，不能因控制改进而扩张**；任何扩张必须重新签发证书。

**P36 阻抗-力可证律（Impedance-Force Certifiability）**
对阻抗控制 `f = K(x_d−x) + D(v_d−v) + f_ff`，在扰动 `‖Δ‖≤Δ_max` 下计算
`F_worst = K·Δx_max + D·Δv_max + F_dist_max`。
证书要求 `F_worst ≤ f_max` 且闭环稳定裕度 `m_s ≥ m_min`；若不可证，则收缩包络或降级为位置控制（即退回 v20）。

**P37 角色-力协同律（Role-Force Coherence）**
交接时角色对 `(r1,r2)` 必须同时满足：① 角色共识（双方对接触区与力预算一致）；② 力分摊 `α·f + (1−α)·f ∈ F_env(r1) ∩ F_env(r2)`；③ 力连续 `|f(t_h⁻) − f(t_h⁺)| ≤ δ_h`。任一不满足则拒绝交接并回退 v20。

## 3. 与基线的接口（如何退化）

- RSB 失效（角色不可判定）⇒ 所有接触视为未授权 ⇒ 退回 v20 零碰撞（更保守）；
- FEC 失效（无力传感 / 摩擦未知）⇒ 力包络收缩为零 ⇒ 退回 v20；
- ICC 失效（增益不可证）⇒ 关闭力控，退回位置控制 + v20；
- RDM 失效（漂移不可检测）⇒ 保守假设角色已漂移 ⇒ 吊销证书；
- CHC 失效（交接无共识）⇒ 禁止交接，退化为单角色执行；
- 全失效 ⇒ 等价 v20；安全继承 `Exec_v21 ⊆ Exec_v20` 由引理 161 保证。

## 4. 预期贡献

1. **角色即证书有效域**：首次把“角色一致性”形式化为证书的**语义有效域**，提出角色签名与证书吊销机制，使“接触权限越界”成为可判定事件；
2. **有界接触安全**：把碰撞证书从“零碰撞”推广为“角色授权下的有界接触安全”，给出力包络、摩擦锥置信下界与力轨迹认证；
3. **阻抗可证化**：给出阻抗-力可证耦合条件，把控制器增益纳入证书，而不是事后验证；
4. **交接窗口安全**：提出多机器人角色交接的角色-力共识与力连续条件，填补“交接瞬间”这一碰撞高发窗口；
5. **安全继承**：保持 `Exec_v21 ⊆ Exec_v20`，实现“语义角色→物理力→可验证接触”的闭环。

## 5. 本轮最大风险

**一句话**：角色一致性只在**标签层**可判定，力包络只在**名义接触模态**下可证；若真实接触模态在标签与力读数都“正常”时静默切换（滑移、楔紧、软物体变形），证书仍会给出 `CONTACT_SAFE`，形成“**角色名义一致、力读数合规、接触模态已漂移**”的语义-物理失配。

```python
# IP-425 Role Signature Binder
@dataclass
class RoleSignature:
    role_id: str
    auth_contact: set          # A_r：授权接触区
    force_budget: ForceBudget  # Φ_r = (f_max, tau_max, rate_max)
    controller_family: str     # C_r
    partners: set              # T_r
    version: int

class RoleSignatureBinder:
    def __init__(self, task_graph, cert_store_v20):
        self.task_graph = task_graph
        self.cert_store = cert_store_v20

    def bind(self, cert, role_sig: RoleSignature):
        """证书只在角色签名下有效；跨角色复用直接拒绝"""
        if cert.role_version is not None and cert.role_version != role_sig.version:
            return None, "ROLE_REBIND_FORBIDDEN"
        cert.role_signature = role_sig
        cert.role_version = role_sig.version
        self.cert_store.put(cert)
        return cert, "OK"

    def consistency(self, n, actual_role, contact_set, force):
        """χ_role：标签 ∧ 接触 ∧ 力 三合一"""
        cert = self.cert_store.get(n)
        if cert is None or cert.role_signature is None:
            return 0
        sig = cert.role_signature
        role_ok = (actual_role == sig.role_id)
        contact_ok = contact_set.issubset(sig.auth_contact)
        force_ok = (force.f_n <= sig.force_budget.f_max
                    and abs(force.tau) <= sig.force_budget.tau_max)
        return 1 if (role_ok and contact_ok and force_ok) else 0

    def revoke_on_switch(self, n, old_role, new_role):
        """角色切换 = 证书吊销事件，而非状态更新"""
        cert = self.cert_store.get(n)
        if cert is None:
            return "NO_CERT"
        if old_role != new_role:
            cert.revoked = True
            return "REVOKED"
        return "UNCHANGED"


# IP-426 Force-Envelope Certificate
class ForceEnvelopeCertificate:
    def __init__(self, mu_hat, sigma_mu, k_mu=3.0, wrench_margin=0.05):
        self.mu_hat = mu_hat
        self.sigma_mu = sigma_mu
        self.k_mu = k_mu
        self.wrench_margin = wrench_margin

    def build_envelope(self, role_sig: RoleSignature, obj, contact_points):
        """保守力包络：摩擦锥用置信下界，力预算用角色上限"""
        mu_min = max(0.0, self.mu_hat - self.k_mu * self.sigma_mu)
        f_max = role_sig.force_budget.f_max
        return ForceEnvelope(
            mu_min=mu_min,
            f_max=f_max,
            tau_max=role_sig.force_budget.tau_max,
            rate_max=role_sig.force_budget.rate_max,
            contact_points=contact_points,
            wrench_margin=self.wrench_margin,
        )

    def certify_trajectory(self, traj, role_sig, obj, env):
        """认证整条力轨迹，而非瞬时力"""
        for k in range(len(traj)):
            w = traj[k]
            if not (0.0 <= w.f_n <= env.f_max):
                return False, "NORMAL_FORCE_OUT"
            if norm(w.f_t) > env.mu_min * w.f_n:
                return False, "FRICTION_CONE_VIOLATED"
            if abs(w.tau) > env.tau_max:
                return False, "TORQUE_OUT"
            if k > 0 and norm(w.f - traj[k - 1].f) > env.rate_max:
                return False, "FORCE_RATE_OUT"
            if not self.wrench_balance(obj, w, env.wrench_margin):
                return False, "OBJECT_SLIP_MARGIN"
        return True, "CONTACT_SAFE"

    def wrench_balance(self, obj, w, margin):
        """物体力平衡：G·f + w_ext = 0 需在摩擦锥内可解，且留裕度"""
        return obj.grasp_matrix().solve(w, margin) is not None

    def intentional_vs_collision(self, w, role_sig, contact_point):
        """有意接触：接触点在 A_r 且力在 Φ_r；否则视为意外碰撞"""
        if contact_point not in role_sig.auth_contact:
            return "UNINTENDED_COLLISION"
        if w.f_n > role_sig.force_budget.f_max:
            return "UNINTENDED_COLLISION"
        return "INTENTIONAL_CONTACT"


# IP-427 Impedance Certificate Coupler
class ImpedanceCertificateCoupler:
    def __init__(self, stability_margin_min=0.2):
        self.stability_margin_min = stability_margin_min

    def worst_case_force(self, gains, delta_x_max, delta_v_max, f_dist_max):
        K, D = gains.K, gains.D
        return K * delta_x_max + D * delta_v_max + f_dist_max

    def certify(self, gains, env, delta_x_max, delta_v_max, f_dist_max):
        f_worst = self.worst_case_force(gains, delta_x_max, delta_v_max, f_dist_max)
        if f_worst > env.f_max:
            return False, "WORST_CASE_FORCE_EXCEEDS_ENVELOPE"
        if gains.stability_margin() < self.stability_margin_min:
            return False, "STABILITY_MARGIN_LOW"
        return True, "IMPEDANCE_CERTIFIED"

    def shrink_or_degrade(self, env, gains, reason):
        """不可证时：先收缩包络，仍不可证则降级为位置控制（退回 v20）"""
        shrunk = env.shrink(factor=0.5)
        if self.certify(gains, shrunk, 0.0, 0.0, 0.0)[0]:
            return shrunk, "ENVELOPE_SHRUNK"
        return None, "FALLBACK_TO_V20_POSITION"


# IP-428 Role Drift Monitor
class RoleDriftMonitor:
    def __init__(self, drift_threshold=0.15, window=5):
        self.drift_threshold = drift_threshold
        self.window = window

    def observe(self, n, contact_pattern, velocity_profile, task_state):
        return RoleObservation(contact_pattern, velocity_profile, task_state)

    def detect(self, n, cert_role, obs):
        """角色漂移：观测特征与证书角色模板的偏离度"""
        template = ROLE_TEMPLATES[cert_role]
        d_contact = jaccard(obs.contact_pattern, template.contact_pattern)
        d_velocity = norm(obs.velocity_profile - template.velocity_profile)
        d_task = 0.0 if obs.task_state == template.task_state else 1.0
        drift = 0.4 * d_contact + 0.3 * d_velocity + 0.3 * d_task
        return drift > self.drift_threshold, drift

    def guard(self, n, cert, obs):
        drifted, score = self.detect(n, cert.role_signature.role_id, obs)
        if drifted:
            cert.revoked = True
            return "ROLE_DRIFT_REVOKED", score
        return "ROLE_CONSISTENT", score


# IP-429 Contact Handover Consensus
class ContactHandoverConsensus:
    def __init__(self, delta_h=0.5):
        self.delta_h = delta_h

    def check_coherence(self, proposal, env1, env2):
        """交接三条件：角色共识 ∧ 力分摊交集 ∧ 力连续"""
        r1, r2, alpha, f, f_prev = proposal

        # 1) 角色共识：双方对接触区与力预算无冲突
        if not (r1.auth_contact & r2.auth_contact).issuperset(f.contact_points):
            return False, "ROLE_CONTACT_DISAGREEMENT"

        # 2) 力分摊必须同时落在双方包络
        f1, f2 = alpha * f, (1.0 - alpha) * f
        if not (env1.contains(f1) and env2.contains(f2)):
            return False, "FORCE_SPLIT_OUT_OF_ENVELOPE"

        # 3) 力连续：交接瞬间不允许冲击
        if norm(f.force - f_prev.force) > self.delta_h:
            return False, "HANDOVER_FORCE_DISCONTINUITY"

        return True, "HANDOVER_SAFE"

    def commit(self, proposal):
        """交接成功：双方角色版本同步递增，旧证书吊销"""
        r1, r2, alpha, f, _ = proposal
        r1.version += 1
        r2.version += 1
        return HandoverCert(r1=r1, r2=r2, alpha=alpha, merkle_root=merkle(proposal))
```

## 3. 推导

**引理 157（角色绑定保守性）** 证书 C 仅在 `χ_role=1` 时有效；`χ_role=1` 要求实际角色等于证书角色、实际接触 ⊆ `A_r`、实际力 ∈ `Φ_r`。角色切换使 `r_n(t) ≠ r_n^cert`，故 `χ_role=0`，C 被吊销。因此不存在“旧角色证书用于新角色”的路径，`Exec_v21 ⊆ Exec_v20` 在语义层成立。∎

**引理 158（力包络保守性）** 由 `μ_min ≤ μ_true` 及 `F_env` 的其余约束均为上界，有 `F_env(r,o) ⊆ F_true(r,o)`（真实安全力集）。故任何通过 `F_env` 的力轨迹在真实摩擦条件下也不会滑出摩擦锥。包络仅允许收缩，故认证只会更保守。∎

**引理 159（阻抗可证性）** 若 `F_worst = K·Δx_max + D·Δv_max + F_dist_max ≤ f_max` 且 `m_s ≥ m_min`，则对任意 `‖Δ‖≤Δ_max`，闭环接触力 `f(t) ≤ F_worst ≤ f_max`，且闭环稳定。故该增益下的接触力始终落在 `F_env`。∎

**引理 160（交接安全性）** 若角色共识、力分摊交集、力连续三条件同时满足，则交接前后总力 `αf+(1−α)f=f` 始终落在双方包络交集内，且 `|f(t_h⁻)−f(t_h⁺)|≤δ_h`，无冲击。故交接窗口内 `ContactSafe` 保持成立。∎

**引理 161（角色-力组合安全继承）** RSB 仅吊销、FEC 仅收缩、ICC 仅收缩或降级、RDM 仅吊销、CHC 仅拒绝交接；任一模块作用都使可执行集合单调不增。故 `Exec_v21 ⊆ Exec_v20 ⊆ Exec_v19`。∎

**引理 162（回退完备性）** 五个模块中任一失效，其退化路径均落在 v20 零碰撞判定或更保守的“全接触未授权”上；全失效时 `Exec_v21 = Exec_v20`。故系统不存在“证书层不可用即失去安全边界”的窗口。∎

## 7. 已知风险与失效模式

1. **摩擦系数系统偏差**：`μ_min` 依赖离线标定，若表面状态变化（水、油、粉尘）导致真实 `μ < μ_min`，则包络偏大、物体滑移。缓解：在线摩擦估计、保守区间摩擦模型、滑移振动检测。
2. **接触模态静默切换**：滑移、楔紧、软物体变形可在力读数“合规”时改变真实接触模态，使 `ContactSafe` 名义成立。缓解：模态分类器、多模态（视觉+触觉）一致性检查、RDM 联合检测。
3. **角色漂移漏检**：观测特征与模板相似但行为已越权（如“夹爪”偷偷变为“推手”）。缓解：接触区硬约束、力预算硬约束、角色心跳与版本号。
4. **阻抗模型失配**：`F_worst` 基于线性阻抗假设，强非线性接触或延迟会使最坏力被低估。缓解：鲁棒上界、延迟补偿、实测峰值反馈校准。
5. **交接竞态**：两机同时更新角色版本，若通信分区，可能各自认为交接成功。缓解：两阶段提交、版本向量、交接超时回滚。
6. **力传感器漂移/饱和**：零漂使 `χ_role` 误判，饱和使包络检查失效。缓解：零漂在线估计、饱和检测、触觉冗余。
7. **角色歧义导致过度保守**：多角色重叠时包络收缩到零，活性骤降。缓解：角色优先级仲裁、分时复用、任务图分解。
8. **可审计性缺口**：角色与力的联合证明若只记录最终 verdict，无法复核中间接触模态。缓解：记录力轨迹摘要、模态标签、角色版本链。

## 8. 本轮最大风险

**一句话**：角色一致性只在**标签层**可判定，力包络只在**名义接触模态**下可证；若真实接触模态在标签与力读数都“正常”时静默切换（滑移、楔紧、软物体变形），证书仍会给出 `CONTACT_SAFE`，形成“**角色名义一致、力读数合规、接触模态已漂移**”的语义-物理失配——这是比 v20“众测协同的系统性误判”更隐蔽的一类“**合规外表下的接触失稳**”。
