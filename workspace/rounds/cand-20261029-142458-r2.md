# 第 13 轮（新循环第 2 轮）· PLACE-CURRICULUM VLA：把「放到哪、何时松手」变成可验证目标，用容差课程把 33k 条成功演示扩成「从粗到细的一族放置任务」

> 检索/复核日期：**2026-10-29（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是灵感循环第 2 轮，三个词是「放置」「视觉语言动作模型」「课程学习」。基线是第 12 轮 **CHUNK-SERVO**；本轮不推倒它，而是补上它默认掉的三个决策：**放到哪、容差多大、什么时候松手**。

## 0. 先给结论：最后 3 厘米之前，还有一个「放置决策」没被建模

截至 2026-10-29，官网首页与 `leaderboard.html` 仍显示 8 行预览数据：MolmoAct 29.7%、WALLOSS 28.5%、DreamZero 27.9%、spirit 25.9%、DM 23.5%、PI 22.8%、GigaBrain 22.6%、gr00t 20.5%；同一页面底部标注「即将发布 / Coming Soon」，直接抓取 `leaderboard_data.json` 返回 **HTTP 567 / SPA 占位页**，不是 JSON。因此这些分数只能当「预览上限 / 难度信号」，不能当 live SOTA、任务难度表或失败分布。这个判断本轮再次成立。

上一轮 CHUNK-SERVO 的判断是：榜首不到 30%，共享瓶颈是「1 秒开环 chunk + 最后 3 厘米没有闭环」。这个判断仍然成立，但它默认了两件事：

1. 机器人知道「放到哪」——目标位姿可以从演示检索或几何估计得到；
2. 机器人知道「什么时候松手」——夹爪开合是一个可以由动作头顺带学出来的标量。

本轮把「放置」这个词拆开后，我认为这两个默认恰恰是 32 个桌面任务里最贵、最容易被平均掉的部分：

- **目标 gap**：语言说「放进文具袋 / 挂到杯架 / 插进第一个插座孔」，模型需要把语言、物体、受器三者对齐；端到端 VLA 把这一步和动作纠缠在同一个 chunk 里，错了也没有中间量可以查。
- **容差 gap**：不同任务的放置容差差两个数量级。纸杯堆叠、试管架、网口是毫米级；果篮、桌面收纳是厘米级；毛巾、书包是变形/遮挡。一个固定精度的策略，在松任务上浪费自由度，在紧任务上不够准。
- **释放 gap**：夹爪开得太早，物体掉落或落在边缘；开得太晚，物体被夹爪带偏或撞到容器。开环 chunk 内没有「释放事件」的显式表示，夹爪标量也没有被校准成「现在可以松手」的概率。

所以本轮的押注是 **PLACE-CURRICULUM VLA（PC-VLA）**：

> 在官方 WLA 的**同一个 checkpoint** 上，加一个放置目标头（预测放置位姿分布、容差和释放概率），用 33k 条成功演示的**释放位姿分布**构建放置码本；用「容差课程」从松到紧地训练目标头、动作头和释放门；在推理时用「精度课程」把 NFE、best-of-N、重规划频率和伺服增益集中到放置阶段——不新增第二个学习模型，不引入外部 VLM/SAM/图像生成器，不依赖 depth/force/tactile。

一句话：**把「放置」从动作末端的一个点，变成一个有分布、有容差、有释放门的可验证目标；用课程学习把 33k 条成功演示从「一条轨迹」扩成「从粗到细的一族放置任务」。**

三个可验证创新点：

1. **PLACE-HEAD + 放置码本**：同一个 VLA checkpoint 输出放置位姿混合分布、容差和释放 logit；码本来自成功演示的释放事件，提供多模态先验和检索兜底。用 G1/G2 验证目标误差、模式覆盖和位置泛化。
2. **容差条件化动作专家 + 容差课程**：把容差 `τ` 作为动作专家的条件 token，训练时从松到紧采样，损失在释放前 `Δ` 秒加权；同一模型在推理时可用大 `τ` 做运输、小 `τ` 做放置。用 G3/G4 验证紧任务涨点且松任务不回归。
3. **释放门 + 测试时精度课程**：释放门由几何门 + 学习稳定性分组成；推理时按阶段分配 NFE、best-of-N、重规划频率和伺服增益；`action_chunk_size` 固定为 5，内部用 30 步 plan 切片。用 G5/G7 验证早释率、p99 延迟和因果消融。

三个灵感词怎么落到方案里：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **放置** | 把放置终点显式建模为 `g = (T_base_ee^g, τ, type)`；码本来自成功演示的释放位姿；释放门决定何时开夹爪 | 不把放置当成动作 chunk 的最后一个点；不做需要 depth/force 的 6D 物体位姿网络 |
| **视觉语言动作模型** | 官方 WLA 同一 checkpoint：VLM 冻结，DiT action head + 放置目标头 + 释放门共享 backbone；目标 token 通过 AdaLN/FiLM 注入动作专家 | 不加载第二个 VLA/世界模型/外部图像生成器；不做逐任务策略 |
| **课程学习** | 三层课程：数据课程（松→紧、支撑→收纳→堆叠→插入/悬挂→变形）、损失课程（释放前加权 + 近失负样本由易到难）、推理课程（运输粗、放置细；NFE/best-of-N/重规划频率按阶段分配） | 不做固定 easy/medium/hard 任务顺序；不把课程当成绩效噱头，必须用 G 门消融 |

### 1.4 API：`action_chunk_size` 是提交级固定值，不能按阶段改

这是本轮最硬、也最容易被忽略的接口事实。提交模板 README（2026-10-29）明确：

- `metadata.action_chunk_size` 是 `int ≥ 1`，**整个提交固定**；每次 `get_action` 返回的每个动作数组 leading time-axis 都等于 `T_a`；evaluator 执行完整个 chunk 才再次调用。
- 因此**不能**在运输阶段返回 15 步、放置阶段返回 3 步；`T_a` 只能提交前选一次。
- 能做到的「双频」是：VLA 内部一次生成 30 步 plan（官方 WLA 默认 chunk 30），提交 `T_a=5`，每次只返回 5 步切片；运输阶段可以连续复用 6 个切片再重规划，放置阶段每个切片都重规划。**变的是重规划频率和内部 NFE，不是 API 的 chunk 长度。**
- 观测：四路 RGB 480×640；双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str`。**没有 depth、camera_info、force/torque、tactile。**
- 动作：`joint` 或 `ee` 互斥；`ee` 模式下 `action.left_ee_pose_gripper_base` / `right_ee_pose_gripper_base` 是**绝对目标位姿**（xyz+rpy，base 系）；另有 `left_gripper`、`right_gripper`、`pivot[7]`。
- 提交须从 8765 起暴露 N 个连续端口；每端口独立 episode、独立 `reset()`；`meta.token` 每次都要带；评测端记录延迟/波动/动作统计。

**对方案的约束**：PC-VLA 的「测试时精度课程」只能改 `plan horizon`（多少个 5 步切片后重规划）、`NFE`、`best-of-N`、伺服增益/开关、图像分辨率/裁剪；不能改 `T_a`。`T_a` 本身要作为提交前的一次性超参数，用 G5/G7 在 3/5/8 中选。

UnifoLM-WLA-1.0 仓库与文档（2026-10-29）：

- 6B 参数；约 2,500 小时真机数据；单模型协调 64 个任务（桌面 + 全身）；支持二指夹爪和多种五指灵巧手。

**战略结论不变**：不要从零训 6B/14B；用官方 WLA Base 做 action-head 微调，把省下的算力投到放置决策、释放门和单任务评测。

### 1.6 外部证据：放置/释放是独立瓶颈，显式目标 + 课程 + 精度分配都有效

本轮重点检索了 2026 年的放置、精度和课程工作（标题/日期均经 arXiv API 或出版页核对）：

- **AnySlot**（arXiv:2604.10432，2026-04-12）：槽位级放置需要「语义选槽 + 厘米级执行」；flat VLA 只会在少数类别上稀疏成功；把语言转成显式空间视觉目标、再用 goal-conditioned VLA 执行，能显著优于 flat VLA 和模块化 grounding。说明「放置目标」值得从动作中拆出来。
- **AnyPlace**（CoRL 2025 / PMLR v305）：两阶段——VLM 先给粗略放置区域，局部模型再预测精确放置位姿；覆盖 insertion / stacking / hanging；纯合成数据训练，真机 16 个放置任务零样本迁移。
- **SpaceVLA**（arXiv:2608.05730，2026-08-06）：用户给定的 grasp/place anchor 把放置成功率从无 anchor 的 50% 提到 91.25%；随机 anchor 降到 77.5%；放置误差 0.7 cm vs 3.4 cm。说明「放置目标的质量」直接决定放置误差。
- **Pointing-VLA**（arXiv:2608.23138，2026-08-24）：typed spatial readout 把 PICK 交给 source-conditioned OFG、PLACE 交给 pointing；作为 π0.5 的空间引导，真实机器人成功率从 52.7% 提到 80.7%。说明「放置」需要独立的阶段化空间接口。
- **SafeManip**（arXiv:2605.12386，2026-05-12）：在 50 个 RoboCasa365 任务、6 个 VLA（含 π0、π0.5、GR00T）上，release stability 是持续高暴露的 temporal safety 类别；常见错误是 off-target release、premature dropping、placement on incompatible surfaces、marginal poses near edges。说明释放/放置不是末端小问题，而是跨模型的主要失败源。
- **PRISM**（arXiv:2610.14704，2026-10-10）：flow-matching 的监督在 context 和 flow time 上被平均，导致「precision demand 高的少数时刻」监督不足（Flow-Time Starvation）；precision-aware reweighting 把三类精密任务的端到端成功率从 38.3% 提到 86.7%。说明「按精度需求加权」是有效的。
- **PACE**（arXiv:2606.00537，2026-05-30）：action chunk 的执行长度与成功率是任务相关、非单调的；从预测 chunk 的速度剖面找 phase boundary、在线选执行 horizon，能提升成功率。说明「分阶段执行」有效，但 UniBot API 固定 `T_a`，只能改重规划频率。
- **CRAFT**（arXiv:2602.12532，2026-02-13）：force-aware curriculum fine-tuning 在接触密集任务上有效；我们没有 force，但可以借用「先约束高熵输入、再逐步放开」的课程思想。
- **SCULPT-VLA**（arXiv:2609.23275，2026-09-20）：staged action grounding + 课程，在分布偏移下 58.1% vs π0.5 的 45.6%。说明「课程 + 结构化中间量」在真实机器人上有效。
- **Libra-VLA**（ACL 2026）与 **CF-VLA**（arXiv:2604.24622，2026-04-27）：coarse-to-fine / 双系统 / 两阶段动作生成，说明「粗到细」既能提精度也能提效率。
- **AffordanceVLA**（arXiv:2606.06155，2026-06-04）：Where2Act 的 2D affordance map + 三阶段 progressive data curriculum；说明「在哪里作用」可以作为中间表示。
- **ForeAct3D**（arXiv:2610.04607，2026-10-03）：语义 3D 监督 + 动作条件未来预测，在「通过高开口放置」和「释放高度」上明显受益；真实放置/插入/序列任务从 6.7% 提到 37.8%。说明放置位置和释放高度需要显式几何。
- **Positional Blind Spots**（arXiv:2608.01573，2026-08-03）：VLA 的失败在空间上是局部聚集的；用 LoRA 在盲区演示上微调，能把总体失败率降 40–85%。说明「按位置/放置模式做课程采样」有依据。

这些工作没有一个是「UniBot 单模型 + 无 depth/force + 固定 chunk + 成功演示-only」的组合。PC-VLA 的差异正在这里。

### 1.7 本轮修正的旧假设

- **旧假设**：测试时可以把 chunk 从 30 降到 5，再在运输时用 15。**修正**：`action_chunk_size` 是提交级固定值；只能在内部用 30 步 plan + 5 步切片，变重规划频率/NFE，不能变 API chunk 长度。
- **旧假设**：放置目标可以从头双目 + 局部 ICP 稳定估计。**修正**：透明/反光/遮挡下不可靠；更稳的是「成功演示的释放位姿码本 + 腕部目标图 + 头双目兜底」，而不是在线 6D 物体位姿网络。
- **旧假设**：夹爪开合可以由动作头顺带学。**修正**：释放是一个独立的二值事件，应该单独建模/校准；否则早释/晚释会被动作损失平均掉。
- **旧假设**：任务难度可以按 Easy/Medium/Hard 排课程。**修正**：对放置而言，更有用的课程维度是**容差**和**放置类型**，而不是官方难度标签；同一 Easy 任务里也可能有毫米级放置。

## 2. 诊断：三个「放置 gap」叠在最后 3 厘米之前

把一次放置失败拆开：

```text
t0: 看到场景 + 语言
t0: VLA 预测 30 步 plan（含放置终点？）
t0+...: 执行 5 步切片；夹爪仍闭合
t_place-0.5s: 接近目标；容差是多少？目标到底在哪？
t_place: 夹爪开——早了吗？晚了吗？
t_place+0.1s: 物体是否稳定？是否在容器内？是否在边缘？
```

三个 gap：

1. **目标 gap**：语言→物体→受器的 grounding 错误。典型：把「第一个插座孔」插到第二个；把「杯架标记位」挂到旁边；把「文具袋」当成「文具盒」。端到端动作头没有中间量，错了只能等失败。
2. **容差 gap**：同一个策略在松任务上过度保守、在紧任务上不够准。典型：纸杯堆叠偏 1 cm 就倒；试管偏 3 mm 就卡；果篮偏 5 cm 也算成功。固定精度/固定增益无法同时覆盖。
3. **释放 gap**：夹爪开合没有被校准成「物体已经落在支持面上/进入容器内/挂住」的事件。典型：物体还在下降就松手；物体碰到容器边缘但没进去就松手；物体被夹爪带出容器后才松手。

为什么现有 VLA 会把它们平均掉：

- **动作损失按时间平均**：30 步 chunk 里，放置前的 2–3 步只占 7–10% 的 loss；flow matching 还在 flow time 上平均（PRISM 的 Flow-Time Starvation）。
- **成功演示只有正样本**：33k 条全是成功；没有「差 2 mm」「早松 0.2 s」的负样本，释放门学不到边界。
- **夹爪是标量**：动作头可以输出 0/1，但没有人告诉它「现在开」对应的是「物体已稳定」还是「物体还在空中」。
- **固定推理预算**：运输和放置用同样的 NFE/分辨率/重规划频率；放置阶段得不到更多计算。
- **单模型规则**：不能为放置再训一个策略；但可以在同一 checkpoint 上加辅助头/条件 token，或用确定性几何门。

失败模式分诊（先验，待单任务通道更新）：

| 失败模式 | 典型任务 | 该投什么 | 不该投什么 |
|---|---|---|---|
| 目标选错（槽位/颜色/顺序） | FruitSorting、ColorArrangement、ArrangePlates、SpellRobot、ConveyorSorting | 放置目标头 + 码本模式 + 语言/视觉检索 | 更大 VLA、更多语义数据 |
| 目标对但差几毫米 | HangCup、ArrangeTestTubes、PlugInEthernet、StackBowls、StoreCups | 容差课程 + 伺服 + 释放门 | 6D 物体位姿网络 |
| 早释/晚释 | PackPhone、StoreEarphones、OrganizeStationery、PackBag | 释放门 + 稳定性检查 | 固定夹爪时序 |
| 放置后不稳/倒/滑 | PaperCupStacking、StackBowls、StorePaddle、SyringeWaterTransfer | 支持面/边缘检查 + 慢放 + 重试 | 只做开环动作 |
| 变形/遮挡/透明 | FoldTowel、ZipUp、PackBag、ToolboxStorage | VLA 基座 + 粗放置 + 不启用精密门 | 纯几何伺服 |
| 位置/人为干扰 | 5 类泛化轴；human_1/4 | 码本相对目标 + 在线重定位 + 恢复 | 固定轨迹 |

## 3. 方法：PC-VLA

### 3.1 总架构

```text
                    ┌──────────────────────────────────────────────┐
                    │ Evaluator (N ports 8765..8765+N-1)           │
                    └───────────────┬──────────────────────────────┘
                                    │ websocket: obs / 5-step chunk
                                    ▼
                    ┌──────────────────────────────────────────────┐
                    │ Per-port PlacementPolicy (CPU)               │
                    │  ├─ phase detector (transport/approach/place)│
                    │  ├─ placement codebook (success release poses)│
                    │  ├─ goal head postprocess + retrieval        │
                    │  ├─ servo (PBVS/IBVS, from CHUNK-SERVO)      │
                    │  ├─ release gate (geometry + stability)      │
                    │  ├─ plan cache (30-step VLA plan, 5-step out)│
                    │  └─ action adapter (WLA 54D → API 21D)       │
                    └───────────────┬──────────────────────────────┘
                                    │ async, batched
                                    ▼
                    ┌──────────────────────────────────────────────┐
                    │ Shared WLA checkpoint (GPU)                  │
                    │  VLM (frozen) + DiT action head (fine-tuned) │
                    │  + placement goal head + release/stability   │
                    │  heads (same checkpoint, shared backbone)    │
                    └──────────────────────────────────────────────┘
```

- **唯一学习模型**：官方 WLA 的同一个 checkpoint；VLM 冻结，DiT action head + goal head + release/stability head 共享 backbone。不是第二个策略。
- **确定性控制器**：视觉伺服、几何释放门、码本检索；无学习权重或只复用同一 checkpoint 的特征。
- **数据资产**：33k 成功演示的释放位姿分布；不是模型，是索引/先验。
- **数字孪生**：只做标定/风洞（外参、RTT、增益、扰动），不训策略。

### 3.2 PLACE-HEAD：放置目标头

定义放置目标：

```text
g = (T_base_ee^g, τ_p, τ_r, type)
```

- `T_base_ee^g`：释放时夹爪在 base 系的期望位姿（xyz + rpy/rotvec）；
- `τ_p, τ_r`：平移/旋转容差；
- `type`：支撑/收纳/堆叠/插入/悬挂/排列/变形。

为什么用绝对 EE 位姿而不是物体 6D 位姿：

- API 的 `ee` 动作就是 base 系绝对 EE 位姿；直接对齐控制接口；
- 数据集没有物体 6D 位姿标注；用释放时 EE 位姿作代理，物体位姿 = EE 位姿 + 已知夹持偏移；
- 透明/反光/遮挡下，物体 6D 位姿网络不可靠；EE 位姿 + 码本更稳。

目标头输出**混合分布**，避免多模态平均：

```text
p(g | o, l) = Σ_{k=1..K} π_k · N(μ_k, Σ_k)
```

- `K` 由码本聚类决定（每任务 1–8 个放置模式）；
- `π_k` 是模式概率；`μ_k` 是模式均值；`Σ_k` 是协方差（对角或全协方差）；
- 额外输出 `r_release ∈ [0,1]`（释放 logit）和 `s_stable ∈ [0,1]`（释放后稳定性分）。

训练目标：

```text
L_goal = -log Σ_k π_k N(g* | μ_k, Σ_k)
L_release = BCE(r_release, 1[t = t_r])
L_stable = BCE(s_stable, 1[object stable after t_r + Δ])
```

- `g*` 来自成功演示的释放帧 `t_r`；
- `t_r` 由夹爪状态/动作的闭合→打开跳变检测；
- `stable` 标签由释放后 0.3–0.5 s 的物体位移/姿态变化阈值定义（可用头双目/腕部图跟踪，或用 EE/夹爪状态兜底）。

码本先验：

- 训练时用码本均值初始化混合分量，或加一个辅助分类损失 `L_mode = CE(k*, π)`；
- 推理时先验 `p(k | task, language)` 与视觉相似度 rerank；
- 当目标头置信度低时，回退到码本 top-k 检索 + CHUNK-SERVO 的腕部目标图。

### 3.3 放置码本：从成功演示里学「一族放置任务」

离线管线：

```text
for each task t:
    for each episode e:
        detect release frame t_r (gripper close→open)
        g_e = T_base_ee(t_r)                 # 释放位姿
        I_e = head/wrist frame at t_r - k     # 目标图
        type_e = task placement type          # 先验标签
    cluster {g_e} in SE(3) with k-means (k by silhouette/BIC, 1..8)
    for each cluster c:
        μ_c = mean pose; Σ_c = covariance
        τ_p,c = q90(||t_i - μ_t||)
        τ_r,c = q90(||Log(R_i^T R_μ)||)
        store μ_c, Σ_c, τ_c, representative image, task/type, quality
```

关键细节：

- **释放检测**：夹爪命令/状态从闭合到打开的跳变；用腕部图像确认物体已离开夹爪；用头双目确认物体在支持面/容器内。三条都满足才算 `t_r`，否则用 `t_r - 1` 或人工抽检。
- **SE(3) 聚类**：平移用欧氏距离，旋转用测地距离；组合距离 `d = ||Δt||/s_p + ||Δr||/s_r`，`s_p/s_r` 用任务中位数归一化。
- **容差**：`q90` 是演示内的经验容差；再与物理间隙估计取 `max`（例如试管架孔半径、网口宽度、杯架槽宽）。物理间隙可以人工标 32 个任务的一张表，成本低、比纯方差稳。
- **多模态**：同一任务可能有多个槽位/颜色/顺序；聚类保留多模式，不要平均成一个。
- **代表图**：取簇 medoid 的释放前 3–5 帧；用于腕部目标图匹配和人工检查。
- **质量分**：簇内样本数、释放检测置信度、物体可见度；低质量簇不进入推理先验，只做训练。

码本的用途：

1. 目标头的模式先验/初始化；
2. 推理时的 top-k 检索兜底；
3. 容差课程的分档依据；
4. 近失负样本的采样中心；
5. 单任务通道的诊断基线（目标误差 vs. 执行误差）。

### 3.4 容差课程：从松到紧，而不是从易到难

课程维度：

1. **容差**：`τ ∈ {>20mm, 5–20mm, 2–5mm, ≤2mm}` 四档；
2. **放置类型**：支撑 → 收纳 → 堆叠 → 插入/悬挂 → 变形/遮挡；
3. **位置/模式**：同一任务内从中心模式到边缘模式、从常见位置到盲区位置（参考 Positional Blind Spots 的结论）。

训练阶段：

| 阶段 | 数据 | 目标头 | 释放门 | 损失权重 |
|---|---|---|---|---|
| C0 | 全部任务，运输/接近段 | 只学粗目标 | 关 | `L_flow` 正常；`L_goal` 0.1 |
| C1 | 支撑/收纳，τ>20mm | 模式分类 + 粗回归 | 几何门 | `L_goal` 0.5；`L_rel` 0.1 |
| C2 | 堆叠/排列，5–20mm | 混合分布 | 几何门 + 易负样本 | `L_goal` 1.0；`L_rel` 0.5 |
| C3 | 插入/悬挂，2–5mm | 混合分布 + 容差条件 | 几何门 + 中负样本 | `L_goal` 1.0；`L_rel` 1.0；释放前加权 |
| C4 | 全部 + 变形/遮挡，≤2mm | 全量 | 几何门 + 难负样本 | 全损失；30% 复习前阶段 |

采样与损失：

```text
p_t ∝ exp(-|log τ_t - log τ_stage| / T)
w_t = clip(1 + λ_prec · 1[t ≥ t_r - Δ] · (τ_ref / τ_t), 1, 5)
L = L_flow + λ_g L_goal + λ_r L_release + λ_s L_stable + λ_c L_mode
```

- `τ_ref` 取 5mm；`Δ` 取 0.5 s（15 帧）；
- 紧容差任务在释放前获得更高权重，但不超过 5×，避免梯度爆炸；
- 每个阶段保留 20–30% 前一阶段数据，防止灾难性遗忘；
- 每阶段结束在全部 32 任务的 held-out episode 上评估，不只看当前阶段。

容差条件化：

- 把 `τ` 编码成 embedding，注入 DiT action head 的 AdaLN/FiLM；
- 训练时对同一 demo 采样 `τ` 的 0.5×/1×/2× 三个值（反事实容差），防止模型把 `τ` 当成任务 ID；
- 推理时：运输 `τ=50mm`，接近 `τ=20mm`，放置 `τ=τ_task`，释放 `τ=τ_task`；
- 辅助校准损失：`L_cal = max(0, ||g - g*|| - τ)^2`，鼓励预测目标落在容差内。

### 3.5 测试时精度课程：把计算花在放置上

因为 `action_chunk_size` 固定，测试时课程只调这些：

| 阶段 | 触发（到目标距离） | 重规划频率 | NFE | best-of-N | 伺服 | 图像 |
|---|---|---:|---:|---:|---|---|
| TRANSPORT | >10 cm | 每 6 个 5 步切片（30 步） | 2 | 1 | 关 | 240×320 |
| APPROACH | 3–10 cm | 每 3 个切片（15 步） | 4 | 1 | PBVS | 240×320 + 腕 128 |
| PLACE | 0.5–3 cm | 每 1 个切片（5 步） | 6 | 2 | PBVS+IBVS | 腕 192 + 头 240×320 |
| RELEASE | 进入容差 | 每 1 个切片 | 6 | 1 | 保持 | 腕 192 |

- `T_a=5` 是提交级固定值；上表的「重规划频率」是内部 plan cache 的行为，不改 API；
- `NFE` 是 DiT 去噪步数；官方默认 4，运输降到 2，放置升到 6；
- `best-of-N` 只在 PLACE 阶段开；用释放门的 `r_release × s_stable` 重排 N 个候选；
- 图像分辨率/裁剪只影响观测传输和视觉特征，不改动作接口；
- 延时预算：`T_fb ≈ T_a/f_c + τ_net + τ_infer`；`T_a=5`、30Hz、RTT 50ms 时约 217ms；NFE 从 2 到 6 会增加推理，但只在放置阶段，且可以用异步 plan cache 隐藏一部分。

预算分配（设计目标，不是实测）：

```text
max_{n_p, h_p} Σ_p π_p S_p(n_p, h_p)
s.t. Σ_p π_p (c_n n_p + c_h h_p) ≤ B
```

- `n_p`：NFE；`h_p`：重规划间隔（切片数）；
- `S_p` 对 `n_p` 递增、对 `h_p` 递减；
- 用贪心边际收益分配：先给 PLACE/RELEASE 加 NFE，再给 APPROACH 缩短 `h_p`；运输保持最低成本；
- 若 p99 超预算，先降 best-of-N，再降 NFE，最后回退 CHUNK-SERVO 的固定 4 NFE。

### 3.6 释放门：几何门 + 稳定性分

几何门（确定性，最稳）：

```text
release_ok = 1[ ||e_p|| ≤ τ_p ] · 1[ ||e_r|| ≤ τ_r ] · 1[ ||v_ee|| ≤ v_max ]
```

- `e_p, e_r`：当前 EE 到目标位姿的平移/旋转误差；
- `τ_p, τ_r`：码本/任务容差；
- `v_ee`：EE 速度估计（相邻帧差分）；太快不松手，避免甩出。

稳定性分（同一 checkpoint 的辅助头，可选）：

```text
s_stable = sigmoid(MLP(z_t, e_p, e_r, support_context))
release_ok &= s_stable > θ_s
```

- 训练正样本：成功演示释放后 0.3–0.5 s 物体位移小于阈值；
- 负样本：释放前帧、扰动目标、边缘/容器外放置；
- 若单模型解释有风险，先用纯几何门，稳定性分只做离线诊断（C2 合规模式）。

释放后检查：

```text
open gripper
wait 0.3 s
track object displacement in head/wrist images
if displacement > δ or object left support:
    re-grasp / retry (max 2)
else:
    done
```

- 透明/变形物体只做粗放置，不启用精密门；
- 人为干扰/目标移动时，先重定位再重新计算 `g`，不要用旧目标松手；
- 任何不确定 → 保持夹爪，回退 VLA 或请求重规划；不要为了省时间硬松手。

### 3.7 与 CHUNK-SERVO 的接口

- **规划**：WLA 一次生成 30 步 plan；PC-VLA 的目标头同时给出 `g`；plan 的末端在适配层被拉向 `g`（软约束，不是硬拼接）。
- **执行**：`T_a=5` 切片；每个切片前用腕部/头部图做一次伺服修正（CHUNK-SERVO 的 IBVS/PBVS）。
- **重规划**：运输每 6 个切片重规划；放置每个切片重规划；目标头在放置阶段每个切片更新一次。
- **码本**：DG-KEYFRAME 从「中间关键帧」升级为「终局释放位姿码本」；中间关键帧仍用于接近阶段。
- **数字孪生**：标定相机外参、腕部内参、伺服增益、RTT；注入位置/遮挡/背景/目标移动/人手扰动；不训大模型。
- **任务组合**：按 `q_t × Δ_t / cost_t` 选任务；`q_t` 现在定义成「失败发生在放置/释放阶段的比例」，比上一轮的「最后 3 厘米」更可测。

### 3.8 数据引擎与伪标签

1. **释放事件**：夹爪闭合→打开 + 腕部物体离开 + 头双目物体在支持面/容器内；三条件投票，人工抽检 100 条。
2. **放置位姿**：`T_base_ee(t_r)`；物体位姿 = EE + 夹持偏移（夹持偏移用夹爪几何/腕部图估计，先验表）。
3. **容差**：簇内 q90 + 32 任务物理间隙人工表；两者取 max；低置信度簇降权。
4. **近失负样本**：对每个正样本 `g*`，在 SE(3) 上扰动 `δ`；`δ` 从 20mm 逐步降到 1mm（课程）；标签为「不在容差内」；不生成图像，只用特征 + 位姿训练释放门/稳定性分。
5. **位置盲区采样**：按码本模式/任务位置分层；对低成功率位置过采样（参考 Positional Blind Spots），但要用 held-out 位置验证，避免过拟合。
6. **数据划分**：按 session/物体/背景/位置分组；相邻帧不跨 split；释放前帧和释放后帧不能分到不同 split。

### 3.9 合规：一个 checkpoint，多个头

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 码本/容差/近失负样本只离线生成；线上只有 WLA + 确定性门 | 最低 | 保守首选 |
| C2 确定性控制器 | 目标头是同一 checkpoint 的辅助输出；释放门是几何规则；伺服无学习权重 | 低 | 主推 |
| C3 同 checkpoint 辅助头 | 释放/稳定性分用共享 backbone 的小头；不加载第二个预训练模型 | 低–中 | 需要强稳定性分时用 |

禁止：加载第二个 VLA/世界模型/外部 VLM/SAM/图像生成器做在线决策；为放置单独训一个策略；用测试集调课程阈值。

- 官方 WLA 基座、33k 演示、官方 rubric、单任务通道。

**升级**：

- DG-KEYFRAME：从「中间关键帧」升级为「终局释放位姿码本」；
- 相位检测：从「接触相位」升级为「运输/接近/放置/释放」四相；
- 伺服目标：从「相对关键帧」升级为「放置目标分布 + 容差」；
- 夹爪：从「动作头标量」升级为「几何门 + 稳定性分」；
- 测试时：从「固定 5 步」升级为「固定 5 步 + 变重规划频率/NFE/best-of-N」；
- 任务组合：`q_t` 从「最后 3 厘米失败比例」升级为「放置/释放失败比例」。

**剪枝**：

- 不做外部图像生成器/外部 VLM/SAM 做在线放置目标（单模型 + 延迟）；
- 不做独立放置策略/第二个学习模型（规则风险）；
- 不做逐阶段变 `action_chunk_size`（API 固定）；
- 不做 force/tactile 课程（API 没有）；
- 不做完整世界模型/视频预测（算力 + 延迟）；
- 不做 6D 物体位姿网络（透明/变形不可靠）；
- 不做 32 任务各一个策略（规则禁止）；
- 不把预览榜单的任务排名当难度表（已证伪）；
- 不把「Easy/Medium/Hard」当课程主轴（对放置不如容差有用）。

**明确不建议继续投**：从零训通用 VLA/World Model、完整 sim-to-real 策略训练、30Hz 广域网视觉伺服、逐任务学习策略、6D 物体位姿网络、力/触觉闭环（API 没有）、外部图像生成目标（单模型/延迟）。这些方向要么已被官方 WLA 覆盖，要么被规则/接口/延迟/数据限制。

## 6. 实验门与竞赛策略

### 6.1 门 G0–G7

| 门 | 问题 | 通过标准 | 失败动作 |
|---|---|---|---|
| G0 | 释放事件能否可靠检测？ | 人工 100 条抽检 F1 ≥0.95；三条件投票一致率 ≥90% | 只用夹爪跳变；放宽到 `t_r-1` |
| G1 | 码本/容差是否可信？ | 每任务 ≥1 个簇 ≥30 样本；跨 split 容差漂移 ≤20%；目标误差 ≤5mm/2° | 合并簇；改用手工容差表 |
| G2 | 目标头是否优于动作末端？ | 目标头 top-1 模式命中 ≥80%；目标误差比直接动作端点低 ≥30% | 只做码本检索；目标头只做先验 |
| G3 | 释放门是否校准？ | AUROC ≥0.85；ECE ≤0.10；固定 TPR 下早释率 ≤5% | 纯几何门；不启用学习门 |
| G4 | 课程是否在仿真有效？ | 紧容差任务 +10pp；松任务不回归 >3pp；无课程基线对比 | 退回 C1；只做数据加权 |
| G5 | 真机单任务是否涨点？ | ≥4/6 任务 +10pp；FoldTowel 不回归 >5pp；p99 ≤150ms | 不提交 PC-VLA；保留 CHUNK-SERVO |
| G6 | 32 任务干跑是否稳定？ | N 端口隔离、reset 干净、内存不涨、token 无误 | 回退基线 |
| G7 | 消融是否支持因果？ | 目标头/课程/释放门/精度课程各自有正贡献；否则砍掉 | 保留有效部分，砍无效部分 |

### 6.2 单任务 A/B

任务：HangCup（悬挂）、StackBowls（堆叠）、PlugInEthernet（插入）、PackPhone（收纳）、FruitSorting（松放置）、FoldTowel（变形防回归）。

- 每个任务 10 次 A/B（PC-VLA vs. CHUNK-SERVO 基线），同一初始条件，顺序随机；
- 指标：成功率、步骤分、放置误差（mm/deg）、早释率、重试次数、p99 延迟；
- 通过：≥4/6 +10pp；FoldTowel 不回归 >5pp；
- 若只有 10 次/任务，配对差值只能看方向；用 bootstrap 95% CI，不要声称 +1–2pp 显著。

### 6.3 竞赛策略

- 320 trials，`p≈0.25` 时全局 SE≈2.42pp；不要用 320 trials 做未验证的 A/B。
- 任务组合：`priority_t = q_t × Δ_t / cost_t`；`q_t` 先用「放置类型/容差」先验，单任务通道后更新。
- 先做 6 个代表任务；若 4 个 +10pp，全局约 +3.75pp（4/32×10）+ human 轴收益；若 10 个 +10pp，+3.1pp；若 19 个 +10pp，+5.9pp。保守目标 +4–7pp，乐观 +8–10pp，但必须用配对 A/B 证明。
- 先交安全基线（若允许多次提交）锁 tie-break；PC-VLA 只在单任务通道过门后提交。
- 步骤分是 tie-break：即使成功率相同，放置/释放更稳也可能提高步骤分；但不要假设 rubric 一定给部分分。

## 7. 风险与合规

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定为第二个模型 | 同一 checkpoint 辅助头；确定性几何门；C1/C2/C3 合规说明 |
| 释放标签噪声 | 门学偏 | 三条件投票 + 100 条人工抽检；低置信度样本降权 |
| 容差标签偏差 | 课程分档错 | 簇内 q90 + 32 任务物理间隙人工表；敏感性分析 |
| 多模态放置 | 目标平均/选错模式 | 混合分布 + 码本分类 + top-k rerank |
| 位置泛化 | 码本过拟合演示位置 | 相对目标/在线重定位；按位置分组划分；盲区过采样 |
| 透明/变形 | 目标估计失败 | 只做粗放置；不启用精密门；VLA 兜底 |
| 延迟 | p99 超预算 | `T_a=5`；NFE/best-of-N 只在放置；异步 plan cache；回退 4 NFE |
| 课程遗忘 | 松任务回归 | 20–30% 复习；每阶段全任务评估；early stop |
| `pivot` 语义 | 下身体不动/动作被拒 | 先零 pivot；用 `example_env.py` 验证；不猜符号 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |
| 数据泄漏 | 离线指标虚高 | session/物体/背景/位置分组；相邻帧不跨 split |
| 预览榜单误导 | 任务组合错 | 只当难度信号；单任务通道更新 `q_t` |

# 第 13 轮产物 · PC-VLA 技术报告：放置目标头、容差课程与释放门

> 检索/复核日期：**2026-10-29（UTC）**。对象：宇树 **UniBot 世界挑战赛**（G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API）。本报告是第 13 轮想法区「PLACE-CURRICULUM VLA（PC-VLA）」的工程化产物；不替换第 12 轮 CHUNK-SERVO，而是在它上面补「放到哪、容差多大、何时松手」三个决策。

## 0. 结论与边界

### 0.1 一句话结论

32 个桌面任务几乎都以「把物体放到某处」收尾，但当前 VLA 把放置目标、容差和释放事件都揉进一个开环 action chunk：目标错了没有中间量可查，容差紧了没有额外精度，夹爪早了/晚了没有校准。PC-VLA 在官方 WLA 的同一个 checkpoint 上加一个放置目标头、一个容差条件化动作专家和一个释放门；用 33k 条成功演示的释放位姿分布构建码本，用「容差课程」从松到紧训练，用「测试时精度课程」把 NFE/best-of-N/重规划频率集中到放置阶段。它不新增第二个学习模型，不依赖 depth/force/tactile，不违反 `action_chunk_size` 固定约束。

### 0.2 证据等级

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A | 官方文档、提交模板、数据集元数据、仓库文档直接核实 | 32 任务、33,276 episodes、`action_chunk_size` 固定、WLA chunk 30、6B/2,500h/64 任务 |
| B | 我们在公开数据/网页上做的分析，可复现 | 释放位姿分档、任务类型计数、榜单预览判断 |
| C | 设计假设，需 G0–G7 验证 | 容差课程 +10pp、释放门 AUROC ≥0.85、p99 ≤150ms |

### 0.3 本轮不做什么

- 不从零训 VLA/World Model；官方 WLA 已开源 6B 基座。
- 不加载第二个学习策略/外部 VLM/SAM/图像生成器做在线放置目标；单模型 + 延迟双重风险。
- 不做完整 sim-to-real 策略训练；数字孪生只做控制器风洞。
- 不做变 `action_chunk_size` 的分阶段执行；API 固定 `T_a`。
- 不做 force/tactile 闭环；API 没有。
- 不做 6D 物体位姿网络处理透明/变形物体；用码本 + 腕部图 + 头双目兜底。
- 不做 32 任务各一个策略；规则禁止，且不泛化。
- 不把预览榜单的任务排名当实测难度；只当先验。

## 1. 事实核对

### 1.1 比赛规则（A）

参赛手册（中文/英文，2026-10-29 经 `r.jina.ai` 抓取）核实：

| 项 | 规则 |
|---|---|
| 模型 | 所有任务须基于**同一模型**完成，不得混合多个模型；模型类型不限（World Model、VLA 均可） |
| 任务 | 32 项桌面任务，涵盖抓取、放置、双手协调 |
| 次数 | 每任务 10 次独立运行 |
| 泛化 | 5 类各 2 次：位置、干扰物、桌面背景、未见物品、人为干扰 |
| 时限 | 单次真机执行上限 **180 s** |
| 排名 | 先比 32 任务总平均成功率；相同看总平均步骤分；再相同看更早提交 |
| 部署 | 评测跨 **N 台机器人**；提交须从 **8765** 起暴露 N 个连续端口；每端口独立交互，`reset()` 状态必须隔离 |
| 测试通道 | 另有**不计分的单任务测试通道**，可用于单任务成功率/步骤分验证 |

**对方案的约束**：PC-VLA 必须是每端口独立、CPU 轻量、不抢 GPU 的控制器；学习部分只能是同一个 WLA checkpoint；单任务通道是唯一敢做 A/B 的地方。

### 1.2 提交 API（A）

提交模板 README（2026-10-29）核实：

| 项 | 规格 |
|---|---|
| 观测图像 | `cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist` 四路 RGB **480×640** |
| 本体 | 双臂关节 `[7]`、EE 位姿 `[6]`（xyz+rpy，base 系）、夹爪 `[1]`、下身体 `[15]`、语言 `str` |
| 动作空间 | `control_space` 仅 `"joint"` 或 `"ee"`，二者互斥 |
| 共享动作 | `action.left_gripper [1]`、`action.right_gripper [1]`、`action.pivot [7]` |
| EE 动作 | `action.left_ee_pose_gripper_base [6]`、`action.right_ee_pose_gripper_base [6]`（绝对目标位姿，xyz+rpy，base 系） |
| chunk | `action_chunk_size` ≥1，**提交级固定**；index 0 先执行，其余顺序执行，直到 evaluator 再次调用 `get_action` |
| token | `metadata.token` 握手校验一次；每次 `get_action` 的 `meta.token` 都要匹配 |
| 缺失 | **没有 depth、camera_info、force/torque、tactile** |
| 监控 | 评测端逐调用记录延迟、波动和动作统计规律，作为结果可信度的一部分 |

**关键推论（本轮修正）**：

- `T_a` 固定意味着**不能按阶段改变 chunk 长度**。上一轮若隐含「运输 15 步、放置 3 步」，在 UniBot API 下不成立。
- 可行的双频是：WLA 内部生成 30 步 plan，提交 `T_a=5`；运输阶段复用 6 个切片再重规划，放置阶段每个切片都重规划。变的是**重规划频率/NFE/best-of-N/伺服**，不是 `T_a`。
- `T_a` 本身要在提交前用 G5/G7 在 3/5/8 中选一次；这是控制参数，不是推理参数。
- 评测端记录 p99 延迟和动作统计；不能为了放置精度把每个 chunk 都拖到 1 s。

## 2. 问题形式化

### 2.1 放置决策

把一次任务写成：

```text
episode = (o_0, l, a_{0:T}, t_r, y)
```

- `o_t`：四路 RGB + 本体 + 语言；
- `l`：任务语言；
- `a_t`：EE 绝对位姿 + 夹爪 + pivot；
- `t_r`：释放帧；
- `y ∈ {0,1}`：任务成功。

定义放置目标：

```text
g = (T_base_ee^g, τ_p, τ_r, type)
```

- `T_base_ee^g`：释放时夹爪在 base 系的期望位姿；
- `τ_p, τ_r`：平移/旋转容差；
- `type`：支撑/收纳/堆叠/插入/悬挂/排列/变形。

放置成功（几何代理）：

```text
y_place = 1[ d_SE3(T_base_ee(t_r), T_base_ee^g) ≤ (τ_p, τ_r) ] · 1[ stable after t_r + Δ ]
```

`d_SE3` 用平移欧氏距离 + 旋转测地距离；`stable` 用释放后 0.3–0.5 s 的物体位移/姿态变化阈值。

### 2.2 三个 gap

**目标 gap**：

```text
g* = argmax_g p(g | o, l)
```

端到端 VLA 没有显式 `g`，只有动作 chunk；语言/物体/受器 grounding 错误会被动作损失平均掉。

**容差 gap**：

```text
π(a | o, l; τ)  # 同一策略在不同 τ 下应表现不同精度
```

固定策略只有一个隐式精度；松任务浪费自由度，紧任务不够准。

**释放 gap**：

```text
r_t = p(release | o_t, g, τ)
```

夹爪标量没有校准成「物体已稳定/进入容器/挂住」的概率；早释/晚释是独立失败模式。

### 2.3 评分与统计

总分：

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j}.
```

320 trials，`p≈0.25`：

```math
\mathrm{SE}(S)\approx \sqrt{\frac{p(1-p)}{320}}\approx 0.0242.
```

即约 **2.4pp**。配对 A/B 的方差取决于任务内相关；报告必须给配对差值的 bootstrap 置信区间，不能只报两个平均值。

人为干扰轴：

```math
\Delta S_{\mathrm{human}} = \frac{2}{10}\,\Delta p_h = 0.2\,\Delta p_h.
```

若 human 轴 +10pp → 全局 +2pp。放置课程若让 10 个紧任务各 +10pp → 全局 +3.1pp；19 个 → +5.9pp。两项叠加的保守目标 +4–7pp；这是设计目标，不是承诺。

### 2.4 失败模式

| 失败模式 | 观测信号 | 可能原因 | PC-VLA 对应模块 |
|---|---|---|---|
| 目标选错 | 动作朝错误槽位/颜色/顺序 | 语言 grounding 错、码本模式选错 | 目标头 + 码本 top-k |
| 差几毫米 | 物体在容器边缘/卡住 | 容差紧、伺服增益不够、目标偏 | 容差课程 + 伺服 |
| 早释 | 物体还在空中就下落 | 夹爪标量未校准 | 释放门 + 速度门 |
| 晚释 | 物体被夹爪带出/撞边 | 释放条件太保守 | 释放门 + 稳定性分 |
| 放置后倒/滑 | 释放后物体位移大 | 支持面/边缘判断错 | 稳定性检查 + 重试 |
| 变形/遮挡 | 目标不可见/形状变 | 6D 位姿/深度失败 | 粗放置 + VLA 兜底 |
| 位置/人为干扰 | 目标被移动/人进入 | 固定轨迹/旧目标 | 在线重定位 + 重规划 |

## 3. 系统设计

### 3.1 进程/端口拓扑

```text
                    ┌──────────────────────────────────────────────┐
                    │ Evaluator (N ports 8765..8765+N-1)           │
                    └───────────────┬──────────────────────────────┘
                                    │ websocket: obs / 5-step chunk
                                    ▼
                    ┌──────────────────────────────────────────────┐
                    │ Per-port PlacementPolicy (CPU)               │
                    │  ├─ phase detector                           │
                    │  ├─ placement codebook (read-only, shared)   │
                    │  ├─ goal postprocess/retrieval               │
                    │  ├─ servo (PBVS/IBVS)                        │
                    │  ├─ release gate + stability check           │
                    │  ├─ plan cache (30-step plan, 5-step output) │
                    │  └─ action adapter (WLA 54D → API 21D)       │
                    └───────────────┬──────────────────────────────┘
                                    │ async, batched
                                    ▼
                    ┌──────────────────────────────────────────────┐
                    │ Shared WLA checkpoint (GPU)                  │
                    │  VLM frozen + DiT action head fine-tuned     │
                    │  + placement goal head + release/stability   │
                    │  heads (same checkpoint, shared backbone)    │
                    └──────────────────────────────────────────────┘
```

- 每个端口一个 `PlacementPolicy` 实例，独立 `reset()`、独立 plan cache、独立 goal 状态。
- 码本只读、共享内存（copy-on-write）；伺服/检索是 CPU 线程，不阻塞 websocket。
- 共享 WLA checkpoint；session ID 区分端口；权重只有一份。
- GPU 6B bf16 约 12GB；一张 24GB/40GB GPU 可服务多个端口，具体并发取决于 batch/序列长度。

### 3.3 模型架构

```text
images ──► VLM (frozen) ──► z_t ──┬──► DiT action head ──► 30-step relative EE + gripper
language ─┘                       ├──► placement goal head ──► mixture (π_k, μ_k, Σ_k), τ, r_release
states ───► state projector ──────┘──► release/stability head ──► r_release, s_stable
```

- VLM 冻结；DiT action head + state projector 按官方 WLA 微调。
- 放置目标头：2–3 层 MLP/Transformer，输入 `z_t` + language embedding + proprioception；输出 `K` 个模式的 `π_k, μ_k, Σ_k`、`τ`、`r_release`。
- 容差 token：`e_τ = MLP(τ)` 注入 DiT 的 AdaLN/FiLM；训练时反事实采样 `τ`，推理时按阶段设 `τ`。
- 释放/稳定性头：2 层 MLP，输入 `z_t` + `e_p,e_r` + 夹爪状态 + 支撑面上下文；输出 `s_stable`。
- 所有头共享同一 checkpoint/backbone；不加载第二个预训练模型。

### 3.4 状态机

```text
INIT ──first obs──► TRANSPORT ──d<10cm──► APPROACH ──d<3cm──► PLACE
  ▲                    │                    │                  │
  │                    │                    │                  ├─ gate ok ──► RELEASE
  │                    │                    │                  │                │
  │                    │                    │                  │                ├─ stable ──► DONE
  │                    │                    │                  │                └─ unstable ──► RECOVER
  │                    │                    │                  │
  │                    └──── replan ────────┴──── replan ──────┘
  │                                                              │
  └──────────────────── edit detection / target moved ◄──────────┘
```

- `TRANSPORT`：远距离，粗目标，低 NFE，长重规划间隔。
- `APPROACH`：3–10 cm，PBVS，中 NFE，中重规划间隔。
- `PLACE`：0.5–3 cm，PBVS+IBVS，高 NFE，best-of-N，逐切片重规划。
- `RELEASE`：进入容差，几何门 + 稳定性分；开夹爪，等待，检查。
- `RECOVER`：目标移动/编辑/释放不稳；停 → 重定位 → 更新 goal → 保守增益重试。

### 3.5 `get_action` 伪代码

```python
class PlacementPolicy:
    def __init__(self, vla, goal_head, release_head, codebook, servo, adapter):
        self.vla = vla
        self.goal_head = goal_head
        self.release_head = release_head
        self.codebook = codebook
        self.servo = servo
        self.adapter = adapter
        self.reset()

    def reset(self):
        self.phase = "TRANSPORT"
        self.plan = None
        self.plan_idx = 0
        self.goal = None
        self.chunks_since_replan = 0
        self.retries = 0
        self.prev_ee = None
        self.released = False

    def metadata(self):
        return {
            "control_space": "ee",
            "obs_delta_indices": OBS_DELTA,
            "image_resize": IMAGE_RESIZE,
            "action_chunk_size": 5,
            "token": os.environ["UNIBOT_SUBMISSION_TOKEN"],
        }

    def get_action(self, obs):
        self._update_phase(obs)
        self._maybe_update_goal(obs)
        self._maybe_replan(obs)

        a_ff = self.plan[self.plan_idx:self.plan_idx + 5]
        if self.phase in ("PLACE", "RELEASE"):
            a_ff = self.servo.correct(a_ff, obs, self.goal)

        release_ok = self._release_gate(obs)
        a_cmd = self.adapter.to_api(
            a_ff, obs, self.goal, release_ok, self.phase
        )

        self.plan_idx += 5
        self.chunks_since_replan += 1
        if self.plan_idx >= len(self.plan):
            self.plan = None
            self.plan_idx = 0
        return a_cmd
```

`_update_phase`：

```python
def _update_phase(self, obs):
    if self.released:
        self.phase = "DONE"
        return
    if self.goal is None:
        self.phase = "TRANSPORT"
        return
    d = se3_distance(obs.ee_pose, self.goal.pose)
    if d > 0.10:
        self.phase = "TRANSPORT"
    elif d > 0.03:
        self.phase = "APPROACH"
    elif d > 0.005:
        self.phase = "PLACE"
    else:
        self.phase = "RELEASE"
```

`_maybe_update_goal`：

```python
def _maybe_update_goal(self, obs):
    if self.phase == "TRANSPORT" and self.goal is not None:
        return
    if self.phase == "TRANSPORT" or self.goal is None:
        dist = self.goal_head.predict(obs)
        cand = self.codebook.topk(obs, task=self.task, k=5)
        self.goal = rerank(dist, cand, obs)
    elif self.phase in ("APPROACH", "PLACE", "RELEASE"):
        # update every chunk near placement
        dist = self.goal_head.predict(obs)
        self.goal = blend(dist, self.goal, alpha=0.5)
```

`_release_gate`：

```python
def _release_gate(self, obs):
    if self.goal is None:
        return False
    e_p = np.linalg.norm(obs.ee_xyz - self.goal.xyz)
    e_r = rotation_angle(obs.ee_rot, self.goal.rot)
    v = ee_speed(obs.ee_pose, self.prev_ee) if self.prev_ee is not None else 0.0
    geom = (e_p <= self.goal.tau_p and
            e_r <= self.goal.tau_r and
            v <= V_MAX)
    if not geom:
        return False
    if self.release_head is None:
        return True
    s = self.release_head.predict(obs, self.goal)
    return s >= THETA_S
```

`to_api`：

```python
def to_api(self, a_rel, obs, goal, release_ok, phase):
    # WLA 30-step plan is relative to plan-time EE; compose to base absolute
    ee_abs = compose_absolute(obs.ee_pose, a_rel)
    # soft-pull the last steps toward the placement goal near placement
    if phase in ("PLACE", "RELEASE"):
        ee_abs = soft_pull(ee_abs, goal.pose, weight=0.3)
    gripper = np.zeros(5)
    if release_ok:
        gripper[:] = 1.0
    return {
        "meta.token": TOKEN,
        "action.left_ee_pose_gripper_base": ee_abs[:, :6],
        "action.right_ee_pose_gripper_base": ee_abs[:, 6:12],
        "action.left_gripper": gripper.reshape(5, 1),
        "action.right_gripper": gripper.reshape(5, 1),
        "action.pivot": np.zeros((5, 7)),
    }
```

### 3.6 动作适配

```text
WLA 54D:
  left_ee_rel[6], left_gripper[1], left_hand[6],
  right_ee_rel[6], right_gripper[1], right_hand[6],
  waist[3], torso[3], base_vxvy[2], base_wz[1],
  base_pose_rel[6], height[1], left_leg[6], right_leg[6]

挑战赛 ee 21D:
  left_ee_abs[6], right_ee_abs[6],
  left_gripper[1], right_gripper[1], pivot[7]
```

映射：

1. `left_ee_abs = compose(T_base_ee_left_current, exp(left_ee_rel))`；转 xyz+rpy。
2. `right_ee_abs` 同理。
3. gripper 直通（校验 0–1 方向）。
4. `pivot = [vx, vy, wz, yaw, pitch, roll, height]` 或官方 server 的 `action.pivot` 语义；**不猜符号**，先用 `example_env.py`/单任务通道验证；不确定返回全零。
5. 腿部/灵巧手在 `ee` 模式下不直接下发。
6. **关键**：WLA 的每个未来动作是「相对 plan-time 当前 EE」；先把整个 30 步 compose 成 base 系绝对目标，再按 5 步切片。否则第 6–30 步会以错误锚点解释，产生系统性偏移。
7. 帧/TCP 风险：WLA 的 EE 帧与挑战赛 `*_ee_pose_gripper_base` 可能差一个 TCP/夹爪长度偏移；用 `example_env.py` 和真实数据做一次手眼/工具坐标校准（平移 ≤1cm、旋转 ≤2°）。这是 G6 的第一验证项。

|---|---|---|---|
| C1 离线标注 | 码本/容差/近失负样本只离线生成；线上只有 WLA + 确定性门 | 最低 | 保守首选 |
| C2 确定性控制器 | 目标头是同一 checkpoint 的辅助输出；释放门是几何规则；伺服无学习权重 | 低 | 主推 |
| C3 同 checkpoint 辅助头 | 释放/稳定性分用共享 backbone 的小头；不加载第二个预训练模型 | 低–中 | 需要强稳定性分时用 |

**禁止**：加载第二个 VLA/世界模型/外部 VLM/SAM/图像生成器做在线决策；为放置单独训一个策略；用测试集调课程阈值；把测试视频/榜单分数当训练信号。

## 4. 放置目标头（PLACE-HEAD）

### 4.1 目标表示

三种可选表示：

| 表示 | 定义 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|
| 绝对 EE | `T_base_ee^g` | 直接对齐 API；标签易得 | 对位置泛化弱 | 默认 |
| 受器相对 | `T_receptacle_ee^g` | 抗位置/人为干扰 | 需受器位姿 | 有余力时加 |
| 模式分类 | `k ∈ {1..K}` + 残差 | 多模态稳；易训练 | 受码本限制 | 默认先做 |

默认实现：**模式分类 + 残差回归 + 容差**。

```text
π = softmax(f_π(z_t, l, s_t))
k* ~ π or argmax
g = μ_{k*} + Δ_θ(z_t, l, s_t, k*)
τ = softplus(f_τ(z_t, l, s_t)) + τ_min
r_release = sigmoid(f_r(z_t, l, s_t, g))
```

- `μ_k` 来自码本；`Δ_θ` 是残差头；
- `τ_min` 取 1mm；`τ` 上限 5cm；
- `r_release` 与释放门共享/独立均可；先独立，便于消融。

### 4.2 放置码本构建

```python
for task in tasks:
    episodes = load_episodes(task)
    goals = []
    for ep in episodes:
        t_r = detect_release(ep)          # gripper close->open + wrist/head checks
        g = ep.ee_pose[t_r]              # base frame
        img = ep.head_left[t_r - 5]      # representative image
        goals.append((g, img, ep.id))
    clusters = se3_kmeans(goals, k_range=1..8, metric=se3_distance)
    for c in clusters:
        mu_t = mean_translation(c)
        mu_R = mean_rotation(c)
        tau_p = quantile(||t_i - mu_t||, 0.9)
        tau_r = quantile(angle(R_i, mu_R), 0.9)
        save(task, c.id, mu_t, mu_R, cov, tau_p, tau_r, medoid_img)
```

关键参数：

- `k`：silhouette/BIC 选 1–8；每簇 ≥30 样本；
- 距离：`d = ||Δt|| / s_p + ||Δr|| / s_r`；`s_p=1cm`、`s_r=5°` 起步；
- 容差：`q90` + 物理间隙表取 max；
- 质量分：簇内样本数、释放检测置信度、物体可见度；
- 低质量簇只做训练先验，不进推理 top-k。

### 4.3 训练目标

```text
L_goal = -log Σ_k π_k N(g* | μ_k, Σ_k)
L_mode = CE(k*, π)
L_res  = Huber(g* - (μ_{k*} + Δ), δ)
L_release = BCE(r_release, 1[t = t_r])
L_cal  = max(0, ||g - g*|| - τ)^2
L_goal_total = L_goal + λ_m L_mode + λ_r L_res + λ_cal L_cal
```

- `g*` 来自释放帧；`k*` 来自码本最近簇；
- `Σ_k` 用对角协方差起步，样本足够后用全协方差；
- `L_cal` 只在训练时用，推理不需要真值；
- 目标头学习率低于 action head（例如 1e-4 vs 5e-5 视配置），避免破坏动作表征。

### 4.4 推理

```text
dist = goal_head(o, l)
cand = codebook.topk(task, language, visual_feature, k=5)
goal = rerank(dist, cand, weights=(0.6, 0.3, 0.1))
if goal.confidence < θ_g:
    goal = codebook.top1(task, language, visual_feature)
if goal is None:
    fallback = CHUNK-SERVO relative keyframe target
    if fallback is None:
        mode = "VLA_OPEN_LOOP"
```

- 任务/阶段过滤优先于外观；不要让颜色直方图把「插网线」匹配到「拔网线」。
- 位置泛化：码本先验 + 在线受器重定位；目标头预测的是当前场景下的绝对位姿，视觉特征应吸收位置变化。
- 人为干扰：检测到目标移动 → 重新预测 `g`，不要用旧目标松手。
- 透明/变形：置信度低 → 粗放置，不启用精密门。

### 4.5 可辨识性条件

只有同时满足才启用精密放置：

1. 目标/受器在头部双目或腕部视野内；
2. 双目 ROI 有效像素 ≥70%，或腕部特征 inlier ≥15；
3. 相机标定误差在门限内（重投影 ≤5px）；
4. 目标位姿协方差低于阈值；
5. 任务属于刚体/半刚体放置（不是纯变形）。

任一条不满足 → 回退 VLA 开环或粗放置；不硬做精密门。

## 5. 容差课程

### 5.1 为什么需要课程

- **成功演示只有正样本**：33k 条全是成功；没有「差 2mm」「早松 0.2s」的负样本。
- **精度需求不均匀**：15 个紧任务、13 个中任务、4 个松任务（先验）；同一任务内，释放前 0.5s 的精度需求远高于运输。
- **flow matching 平均**：30 步 chunk + flow time 平均，释放前少数步的监督被稀释（PRISM 的 Flow-Time Starvation）。
- **固定精度不可能覆盖两个数量级**：2mm–50mm 的容差需要条件化/课程化，而不是一个固定策略。

### 5.4 课程阶段

| 阶段 | 数据 | 目标头 | 释放门 | 损失 |
|---|---|---|---|---|
| C0 | 全部任务，运输/接近 | 粗目标 | 关 | `L_flow` 正常；`L_goal` 0.1 |
| C1 | 支撑/收纳，τ>20mm | 模式 + 粗回归 | 几何门 | `L_goal` 0.5；`L_rel` 0.1 |
| C2 | 堆叠/排列，5–20mm | 混合分布 | 几何 + 易负 | `L_goal` 1.0；`L_rel` 0.5 |
| C3 | 插入/悬挂，2–5mm | 混合 + 容差条件 | 几何 + 中负 | `L_goal` 1.0；`L_rel` 1.0；释放前加权 |
| C4 | 全部 + 变形/遮挡，≤2mm | 全量 | 几何 + 难负 | 全损失；30% 复习 |

采样：

```text
p_t ∝ exp(-|log τ_t - log τ_stage| / T)
```

- `τ_stage` 从 5cm 逐步降到 2mm；
- `T` 从 1.0 降到 0.3，先宽后窄；
- 每 batch 至少 20% 来自前一阶段（复习）；
- 每阶段结束在全部 32 任务的 held-out episode 上评估。

### 5.5 损失

```text
w_t = clip(1 + λ_prec · 1[t ≥ t_r - Δ] · (τ_ref / τ_t), 1, 5)
L_flow = E[ w_t · || v_θ(x_t, t | o, l, g, τ) - (x_1 - x_0) ||^2 ]
L = L_flow + λ_g L_goal_total + λ_r L_release + λ_s L_stable
```

- `τ_ref=5mm`；`Δ=0.5s`；`λ_prec=1.0` 起步；
- 权重上限 5，避免紧任务梯度爆炸；
- `λ_g` 从 0.1 升到 1.0；`λ_r` 从 0 升到 1.0；`λ_s` 从 0 升到 0.5；
- 每个阶段重新归一化损失，避免阶段间尺度跳变。

### 5.6 近失负样本课程

对每个正样本 `g*`：

```text
for stage in [20mm, 10mm, 5mm, 2mm, 1mm]:
    δ ~ Uniform(0, stage) in translation; rotation ~ Uniform(0, stage/10)
    g_neg = g* + δ
    label = 0 if ||δ|| > τ else 1  # boundary-aware
```

- 只扰动位姿，不生成图像；释放门输入是特征 + 位姿，不需要像素级负样本。
- 课程从大扰动到小扰动，让门先学粗边界，再学毫米级边界。
- 加入「释放前帧」作为天然负样本（物体还在夹爪里/还在空中）。
- 加入「容器外/边缘」几何负样本（如果码本/物理间隙能标注）。
- 验证集用不同扰动种子；不要用测试集调阈值。

### 5.7 复习与遗忘控制

- 每阶段 20–30% 前一阶段数据；
- 每阶段结束在全部 32 任务上评估；如果松任务回归 >3pp，回退学习率/增加复习；
- 用 LoRA 或低学习率保护基座；只训 action head + 新头；
- 早停看在 held-out 任务上的平均成功率 + 紧任务成功率，不只看训练 loss。

## 6. 测试时精度课程

### 6.1 固定 chunk 约束

`action_chunk_size` 是提交级固定值，不能按阶段变。可行的控制维度：

| 维度 | 可否变 | 说明 |
|---|---|---|
| `T_a` | 否（提交级） | 提交前在 3/5/8 中选一次 |
| 重规划间隔 `h` | 是 | 每多少个 5 步切片重新调用 VLA |
| NFE | 是 | 2/4/6 |
| best-of-N | 是 | 1/2/4 |
| 伺服增益/开关 | 是 | PBVS/IBVS/关 |
| 图像分辨率/裁剪 | 是 | 传输 resize + 策略内裁剪 |
| `pivot` | 是 | 但语义未验证；先零 |

### 6.2 相位检测

```text
d = se3_distance(current_ee, goal)
if d > 0.10: TRANSPORT
elif d > 0.03: APPROACH
elif d > 0.005: PLACE
else: RELEASE
```

补充信号：

- 目标头置信度低 → 保持 APPROACH，不进入 PLACE；
- 编辑检测（GEO-RESIDUAL）触发 → RECOVER；
- 夹爪滑移/物体残差突变 → 重抓；
- 透明/变形任务 → 只到 APPROACH，不启用精密门。

### 6.3 计算分配表

| 阶段 | 重规划间隔 | NFE | best-of-N | 伺服 | 图像 | 目的 |
|---|---:|---:|---:|---|---|---|
| TRANSPORT | 6 切片（30 步） | 2 | 1 | 关 | 240×320 | 吞吐 |
| APPROACH | 3 切片（15 步） | 4 | 1 | PBVS | 240×320 + 腕 128 | 接近 |
| PLACE | 1 切片（5 步） | 6 | 2 | PBVS+IBVS | 腕 192 + 头 240×320 | 精度 |
| RELEASE | 1 切片（5 步） | 6 | 1 | 保持 | 腕 192 | 释放 |

- `best-of-N` 用释放门的 `r_release × s_stable` 重排；N=2 是延迟/收益折中，N=4 只在离线/高预算时试。
- 如果 p99 超 150ms：先降 best-of-N 到 1，再降 NFE 到 4，最后回退 CHUNK-SERVO 固定 4 NFE。
- 如果 RTT 高（>100ms）：放置阶段也保持 `h=1`，但降低伺服增益；不要用高增益追延迟。

### 6.4 预算分配推导

设阶段 `p` 的占比 `π_p`，NFE `n_p`，重规划间隔 `h_p`，成功概率 `S_p(n_p, h_p)`：

```math
\max_{\{n_p,h_p\}} \sum_p \pi_p S_p(n_p,h_p)
\quad \text{s.t.} \quad
\sum_p \pi_p (c_n n_p + c_h h_p) \le B.
```

- `S_p` 对 `n_p` 递增（更准的去噪），对 `h_p` 递减（反馈更慢）；
- `c_n`：每 NFE 的推理成本；`c_h`：每次重规划的通信/推理成本；
- 拉格朗日条件：`(∂S_p/∂n_p)/c_n = (∂S_p/∂h_p)/c_h = λ`；
- 实践中用贪心：从运输开始最低配置，按边际收益/成本把预算移到 PLACE/RELEASE，直到用完。

一个直观结论：**放置阶段的边际收益最高，因为 `S_p` 对 `h_p` 最敏感（容差小、接触事件短）；运输阶段对 `h_p` 不敏感（自由空间、长距离）。** 所以固定 `T_a=5` 后，把「重规划频率」和「NFE」向放置倾斜是合理的。

### 6.5 延迟模型

```math
T_{\mathrm{fb}} \approx \frac{T_a}{f_c} + \tau_{\mathrm{net}} + \tau_{\mathrm{infer}}.
```

| 场景 | `T_a` | `f_c` | `τ_net` | `τ_infer` | `T_fb` |
|---|---:|---:|---:|---:|---:|
| 运输（2 NFE） | 5 | 30 | 50ms | 40ms | **257ms** |
| 放置（6 NFE） | 5 | 30 | 50ms | 100ms | **317ms** |
| 高 RTT | 5 | 30 | 150ms | 100ms | **417ms** |
| 低 RTT | 5 | 30 | 20ms | 100ms | **287ms** |
| `T_a=3` | 3 | 30 | 50ms | 100ms | **250ms** |

- 这些是数量级估算，必须用 G5 实测；
- `T_a=3` 反馈更快，但通信/推理次数增加；`T_a=8` 更省但更慢；提交前扫一次；
- 评测端记录 p99；不要让放置阶段的 best-of-N 把 p99 推到 300ms 以上。

### 6.6 best-of-N 与释放门

```text
candidates = action_head.sample(o, l, g, τ, N)
scores = [release_gate(o, g, a) for a in candidates]
a* = argmax score
```

- 只在 PLACE 阶段开；
- 评分 = `r_release × s_stable × exp(-servo_error)`；
- 如果所有候选分数低于阈值，回退到 VLA 原始动作 + 几何门；
- N=2 的额外推理约 1 倍 action head 前向；6B VLM 已算过，action head 是小头，成本可控。

## 7. 释放门与稳定性检查

### 7.1 标签

正样本：

- 成功演示的释放帧 `t_r`；
- 释放后 0.3–0.5 s 物体位移 < `δ_stable`（例如 5mm）且姿态变化 < `δ_rot`（例如 5°）。

负样本：

- 释放前 `Δt = 0.2/0.5/1.0 s` 的帧；
- 近失扰动目标（5/10/20mm）；
- 容器外/边缘放置（几何标注）；
- 释放后物体位移大的帧（如果数据里有；成功演示里很少）。

### 7.2 几何门

```text
e_p = ||t_ee - t_goal||
e_r = angle(R_ee, R_goal)
v = ||t_ee(t) - t_ee(t-1)|| * f_c
geom = (e_p <= τ_p) and (e_r <= τ_r) and (v <= V_MAX)
```

- `τ_p, τ_r` 来自码本/任务；
- `V_MAX` 例如 0.05 m/s（放置段慢速）；
- 几何门是确定性、可解释、零学习风险的；先上线它，再加稳定性分。

### 7.3 稳定性分

```text
s_stable = sigmoid(MLP([z_t, e_p, e_r, gripper, support_context]))
```

- `support_context`：目标附近的视觉特征/平面/容器边缘；可以用头双目深度或腕部图；
- 训练：正样本释放后稳定；负样本近失/边缘/释放前；
- 推理：`release_ok = geom and s_stable > θ_s`；
- 校准：用 held-out 任务画 reliability diagram；`θ_s` 按目标早释率选（例如 ≤5%）。

### 7.4 校准

- 释放门输出概率，不是分数；用 Platt scaling/等渗回归校准；
- 指标：AUROC、AUPRC、ECE、固定 TPR 下的 FPR；
- 通过标准：AUROC ≥0.85、ECE ≤0.10、早释率 ≤5%；
- 如果校准差，退回纯几何门；不要用未校准的分数直接开夹爪。

### 7.5 释放后检查

```text
open gripper
wait 0.3 s
track object displacement in head/wrist images
if displacement > δ or object left support:
    re-grasp (if object still reachable) or retry placement
else:
    done
```

- 透明/变形物体：只做粗放置，不启用精密检查；
- 人为干扰：先重定位，再重新计算 `g`；
- 安全：最大重试 2 次；限速/限幅；不确定时保持夹爪。

### 7.6 恢复

```text
if edit_score > θ_e or goal_moved > δ_g:
    hold position
    re-localize target with head stereo / codebook retrieval
    if visible:
        update goal; resume with conservative gain
    else:
        request VLA re-plan with new image + language
    if retries > max:
        fail gracefully
```

- 恢复不需要识别人类；只需要「场景动了，而且不是我的动作解释的」；
- 人为干扰轴占 20%；这是性价比最高的单项。

## 8. 数据引擎

### 8.1 释放事件检测

```python
def detect_release(ep):
    # 1. gripper command/state close->open
    g = ep.gripper  # (T,)
    cand = [t for t in range(1, T) if g[t-1] < 0.2 and g[t] > 0.8]
    # 2. wrist object leaves gripper (visual check)
    # 3. head stereo object on support/in container (optional)
    for t in cand:
        if wrist_object_left(ep, t) and head_object_placed(ep, t):
            return t
    return cand[0] if cand else None
```

- 三条件投票；人工抽检 100 条；
- 失败样本（没有释放/一直夹着）标记为无效，不进码本；
- 释放帧可能比真实物体离手早 1–3 帧；用 `t_r` 和 `t_r+2` 做敏感性分析。

### 8.2 码本统计

每个任务输出：

| 字段 | 含义 |
|---|---|
| `n_episodes` | 参与聚类的 episode 数 |
| `k` | 模式数 |
| `π_k` | 模式占比 |
| `μ_t, μ_R` | 模式均值 |
| `Σ` | 协方差 |
| `τ_p, τ_r` | 90% 容差 |
| `medoid_img` | 代表图 |
| `quality` | 样本数/置信度/可见度 |

预期：紧任务 1–3 个模式；松任务 3–8 个模式（多个槽位/位置）。簇不平衡时，按 `π_k` 加权采样，不要过采样小簇到失真。

### 8.3 近失生成

```python
def make_near_miss(g, tau, stage):
    d = np.random.uniform(0, stage)
    direction = random_unit_vector()
    t_neg = g.t + d * direction
    r_neg = g.R @ exp(random_rotvec(max_angle=stage/10))
    label = 0 if d > tau else 1
    return Pose(t_neg, r_neg), label
```

- stage 序列：20mm → 10mm → 5mm → 2mm → 1mm；
- 每个正样本生成 5–10 个负样本；按阶段 curriculum 采样；
- 验证集用不同 seed；不要用测试集调 stage。

### 8.4 数据划分与泄漏

- 按 session/物体/背景/位置分组；相邻帧不跨 split；
- 释放前帧和释放后帧不能分到不同 split（否则释放门泄漏）；
- 同一任务的不同模式可以跨 split，但要保证每个模式在训练集出现；
- 位置泛化：留出整片区域/整类位置，不要只留随机帧。

### 8.5 可选仿真增强

- 用 MuJoCo/IsaacLab 搭 3 个放置族：peg-in-hole、stack/hang、containment；
- 用仿真生成近失/失败轨迹，训练释放门/稳定性分；
- 仿真只做控制器风洞和负样本，不训大 VLA；
- sim-to-real gap 只影响阈值/增益，不影响策略分布。

## 10. 竞赛策略

### 10.1 任务组合

```text
priority_t = q_t * Δ_t / cost_t
```

- `q_t`：失败发生在放置/释放阶段的比例（先验 + 单任务通道更新）；
- `Δ_t`：PC-VLA 条件增益（A/B 差值）；
- `cost_t`：码本/容差/标定/评测成本。

先做 6 个代表任务：HangCup、StackBowls、PlugInEthernet、PackPhone、FruitSorting、FoldTowel。它们覆盖悬挂、堆叠、插入、收纳、松放置、变形，能最快看出 PC-VLA 是否只在紧任务有效、是否伤害松/变形任务。

### 10.2 单任务协议

1. 选 6 个任务；每任务 10 次 A/B（PC-VLA vs CHUNK-SERVO）。
2. 同一初始条件；尽量配对；顺序随机。
3. 记录成功、步骤分、放置误差、早释率、重试、p99。
4. 通过：≥4/6 +10pp；FoldTowel 不回归 >5pp。
5. 再扫 `T_a=3/5/8`、NFE、best-of-N；选 p99 和成功率的最佳折中。
6. 最后跑 32×10 正式评测。

### 10.3 提交节奏

- W0：官方 WLA + API adapter + `T_a=5` 基线；单任务通道跑 1 个任务，确认 token/`pivot`/动作形状。
- W1：安全基线提交（若允许多次）；锁“更早提交” tie-break。
- W2–W4：释放码本、目标头、释放门、课程；单任务 A/B。
- W5：精度课程/超参扫描；32 任务干跑。
- W6：最终提交；保留回滚开关。

若只允许一次提交：跳过 W1，W5 后再交；不要用正式 320 trials 做未验证 A/B。

### 10.4 资源预算

| 方案 | 成本（估算） | 预期收益 | 建议 |
|---|---|---|---|
| WLA 直接适配 | 1–2 人周 | 基线；可能 20–30% | 必做 |
| WLA action-head 微调 | 2–3 GPU 周 + 1 人周 | +1–3pp（未知） | 做 |
| PC-VLA（目标头+课程+释放门） | 4–5 人周 + 2 GPU 周 | 紧任务 +10–15pp → 全局 +3–5pp；human +1–2pp | 主投 |
| 完整世界模型 | 8+ GPU 周 | 不确定；延迟更差 | 不做 |
| 32 任务各训策略 | 规则禁止 | — | 不做 |

## 11. 风险与合规

### 11.1 单模型合规

- 一个 checkpoint：VLM + DiT action head + 目标头 + 释放/稳定性头；共享 backbone。
- 码本是数据索引，不是模型；伺服是确定性控制器；几何门是规则。
- 不加载第二个预训练模型/外部 VLM/SAM/图像生成器。
- 提交材料写清楚：哪些是学习参数、哪些是规则、哪些是离线数据。
- 如果官方对「模型」作最严解释，先用 C1/C2：目标头只做辅助输出，释放门纯几何，稳定性分只离线诊断。

### 11.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单模型解释 | 被判定为第二个模型 | C1/C2/C3；提交说明；确定性回退 |
| 释放标签噪声 | 门学偏 | 三条件投票 + 100 条抽检；低置信度降权 |
| 容差标签偏差 | 课程分档错 | q90 + 物理间隙表；敏感性分析 |
| 多模态放置 | 目标平均/选错 | 混合分布 + 码本分类 + top-k rerank |
| 位置泛化 | 码本过拟合 | 相对目标/在线重定位；位置分组；盲区采样 |
| 透明/变形 | 目标估计失败 | 粗放置；不启用精密门；VLA 兜底 |
| 延迟 | p99 超预算 | `T_a=5`；NFE/best-of-N 只在放置；异步 cache；回退 |
| 课程遗忘 | 松任务回归 | 20–30% 复习；全任务评估；早停 |
| `pivot` 语义 | 下身体不动/动作被拒 | 零 pivot；`example_env.py` 验证；不猜符号 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B；bootstrap；重复；SE≈2.4pp |
| 数据泄漏 | 离线指标虚高 | session/物体/背景/位置分组；相邻帧不跨 split |
| 预览榜单误导 | 任务组合错 | 只当难度信号；单任务通道更新 `q_t` |
| 安全 | 碰撞/掉落 | 限速/限幅；最大重试；不确定保持夹爪 |

### 11.3 安全

- 放置段限速 `V_MAX`；接近段降速；接触段法向缩幅。
- 释放前检查 `v_ee`；太快不松手。
- 释放后检查稳定性；不稳重试，最多 2 次。
- 人为干扰/目标移动：先停，再重定位；不要追。
- 任何异常返回上一组合法动作或安全 hold；绝不返回 NaN/错误形状。

- 把 Easy/Medium/Hard 当课程主轴（对放置不如容差有用）。
- 把预览榜单任务排名当难度表（已证伪）。

**本轮修剪理由**：

- AnySlot 式的「外部图像生成器渲染目标」很有效，但在 UniBot 单模型 + 远程 API 下会引入第二个模型和额外延迟；改为同一 checkpoint 的目标头 + 码本。
- PACE 式的「在线选 chunk 执行长度」在 UniBot 下不成立，因为 `action_chunk_size` 固定；改为「重规划间隔/NFE/best-of-N」课程。
- CRAFT 式的「force-first 课程」没有 force 传感器；借课程思想，不借传感器。
- 6D 物体位姿网络对透明/反光/变形不可靠；改为 EE 释放位姿代理 + 码本 + 腕部图。
