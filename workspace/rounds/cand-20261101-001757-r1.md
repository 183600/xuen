# 新循环 R1（总第 13 轮）· INTENT-BUS：把自然语言指令编译成偏序目标合同，用策略侧 ROS2 截止时间总线调度 VLA/伺服/观察

> 日期：**2026-11-01（UTC）**。承接第 10 轮 FACT-VLA、第 11 轮 GEO-RESIDUAL、第 12 轮 CHUNK-SERVO。本轮三个灵感词是**意图理解**、**机器人操作系统**、**自然语言指令**。本轮不重新抓取赛事网页；A 级赛事事实沿用第 12 轮 2026-10-28 的核实结果，新增的是语言/系统分析（B 级）与设计假设（C 级）。

## 0. 先给结论：CHUNK-SERVO 解决了「多久看一次」，还没解决「看什么、做到哪、被打断后做什么」

第 12 轮把 30 步开环 chunk 改成「30 步规划 + 5 步视觉伺服」，这是正确的控制层增量。但它把语言当成一个**条件字符串**：VLA 读它，控制器不读它。控制器只知道「任务 id + 相位 id + 检索到的相对位姿」，不知道：

1. **当前子目标到底是什么**。挂杯是「杯柄对准钩子」还是「杯口套进钩子」？插网线是「插头对准端口」还是「线缆先绕过挡板」？没有显式谓词，5 步伺服只能在任务级目标上修，不能按子目标切换控制模式。
2. **什么时候算完成**。CHUNK-SERVO 的相位机是手工的；成功由 evaluator 判定，运行时没有自己的验证谓词。于是它无法判断「人已经把杯子挂上去了，不用重做」，也无法判断「已经插到位，应该松手后退」。
3. **语言欠定时该抓哪一个**。「把杯子挂到架子上」在有两个杯子、两个钩子时是欠定的；检索分数最高不等于任务成功概率最高。第 12 轮没有显式的歧义信念，也没有「先看一眼再决定」的机制。
4. **多个异步模块如何在截止时间下不打架**。VLA 请求、腕部/头部感知、目标检索、伺服、编辑检测、安全守卫都在同一个端口里；第 12 轮只有「异步、可批处理」一句，没有 QoS、没有 deadline、没有端口隔离契约。N 台机器人并发时，p99 是最先崩的东西。

本轮的押注是 **INTENT-BUS**：

> 把自然语言指令编译成一张**偏序目标图（Partially Ordered Goal Graph, POGG）**——每个节点有前置条件、验证谓词、检索角色、控制模式、超时与恢复边；把这张图放进一个**策略侧的操作系统运行时**：热路径（伺服/仲裁）在进程内零拷贝，冷路径（意图编译/接地/检索/VLA）跑在 ROS2 或等价的 AsyncBus 上；用截止时间感知的仲裁器在 VLA、伺服、观察、保持之间选动作；用歧义信念与有界价值信息（VOI）决定「先看还是先做」；用意图修复而不是盲目重定位来处理人为干扰。

一句话：**语言不是标签，是合同；ROS 不是提交接口，是策略侧截止时间总线；伺服不是任务级微调，是合同激活节点上的条件闭环。**

三个可验证创新点：

1. **意图合同编译器**：用受限文法 + 32 任务本体，把指令编译成 POGG；每个节点带 `pre/post/role/control/deadline`；不新增学习模型。用 I0/I1 验证覆盖率和接地精度。
2. **策略侧截止时间总线**：热/冷路径分离；ROS2（可选）或 AsyncBus；QoS deadline/liveliness；每端口命名空间隔离；用 I3 验证 p99/N 端口/超时。
3. **信念空间执行与意图修复**：歧义用 `b(h)` 表示，VOI 决定是否做一次有界观察；人为编辑触发受影响节点的重新接地、谓词复查、跳过/重做/放弃；用 I4/I5 验证恢复与涨点。

三个灵感词怎么落地：

| 灵感词 | 落到哪里 | 不做什么 |
|---|---|---|
| **意图理解** | 语言 → 类型化语义框架 → POGG；每个节点是可验证谓词，不是隐式相位；歧义用信念与 VOI 处理 | 不训第二个 LLM/VLM 规划器；不做开放域对话；不声称读懂任意自然语言 |
| **机器人操作系统** | 策略侧运行时：合同=进程、POGG=程序、技能=系统调用、仲裁器=调度器、人工编辑=中断、端口=地址空间、180s=watchdog；ROS2 只做内部中间件 | 不在 G1 上装 ROS；不把 ROS2 当提交接口；不让 DDS 进热路径；不假设评测容器一定有 ROS2 |
| **自然语言指令** | 受限文法 + 双语同义词 + 32 任务本体；多从句按时间连词合并；属性/空间关系接地；OOD 语言回退 VLA | 不做通用语义解析；不把语言当唯一真理；不让解析失败阻塞执行 |

## 1. 直觉：人接到一句话，先建合同，再动手

想象你对一个熟练的桌面操作员说：「把网线插进左边那个端口，插到底，然后松手。」

他不会只把这句话编码成一个动作向量。他会同时建立四层东西：

- **指称**：哪根网线、哪个端口；「左边」是相对谁；如果有两个端口，先确认是哪一个。
- **子目标偏序**：先找线、抓线、抬起、接近端口、对准、插入、验证、松手、后退；没抓住不能插，没对准不能硬推。
- **成功谓词**：插头进入端口到一定深度、松手后线还连着；不是「动作做完了」。
- **恢复语义**：插不进去时先退 1 cm 重新对准，而不是继续加力；人把线拿走时，先停、再看、再决定。

这四层东西，正是 VLA 的 action chunk 不显式携带的。VLA 在 33k 成功演示上学到了「像什么」，但没有一个控制器可读的「合同」。**意图理解的价值不是让模型更懂语言，而是把语言里已经写明的约束变成运行时可以检查、可以恢复、可以拒绝执行的对象。**

操作系统类比也不是修辞，而是接口设计：

| OS 概念 | INTENT-BUS 对应 |
|---|---|
| 进程 / 程序 | 一个任务会话 / 一张 POGG |
| 系统调用 | VLA 规划、目标检索、伺服、验证、观察 |
| 调度器 | 截止时间感知的仲裁器 |
| 中断 | 人为编辑、谓词失效、安全风险 |
| 地址空间隔离 | 每端口独立合同/信念/缓存；`reset()` 清空 |
| watchdog | 180 s、chunk 超时、感知 stale |
| 可观测性 | 事件日志、p99、合同进度、修复次数 |

**关键设计约束**：赛事只认 Python `PolicyService`，且规则要求同一模型。因此 ROS2 只能是**策略容器内部**的中间件，不能是提交接口；意图编译器必须是确定性的文法/本体，不能是第二个学习模型；所有学习能力仍来自官方 WLA。这样既拿到 OS 的调度/隔离/可观测性，又不碰合规红线。

## 2. CHUNK-SERVO 留下的三个结构性缺口

### 2.1 语义缺口：相位是手工的，谓词是缺失的

第 12 轮的状态机是 `INIT → PLAN → SERVO → CONTACT → RECOVER → DONE`。它知道「接触段要缩幅」，但不知道「当前接触的是杯柄还是杯口」「插的是网线还是充电器」「这一步对应官方 rubric 的哪一步」。结果是：

- 伺服目标只能按任务/相位检索，不能按**语义角色**检索；
- 接触段的控制模式是全局的，不能按节点类型切换（插入 vs 挂 vs 叠 vs 拉拉链）；
- 失败恢复只能回到「上一个相位」，不能判断「这个子目标其实已经由人完成了」。

### 2.2 运行时缺口：异步不等于实时

第 12 轮的每端口 `PolicyService` 里同时跑：相位/编辑观察、目标检索、视觉伺服、plan cache、动作适配。它说「异步、可批处理」，但没有回答：

- VLA 请求超时了，`get_action` 还能不能按时返回？
- 感知线程落后 200 ms，伺服该不该用旧图？
- N 个端口同时抢 CPU，p99 是多少？
- `reset()` 时哪些缓存必须清、哪些可以共享？
- 哪个模块的延迟算进「评测端记录的逐调用延迟」？

这些不是部署细节，是**算法能否在真实截止时间下成立**的一部分。一个在离线回放里收敛的伺服，如果在 p99 上超时，等于不存在。

### 2.3 歧义缺口：检索分数不是成功概率

「把杯子挂到架子上」在多个杯子/多个钩子时是欠定的。第 12 轮用描述子距离 + 相对位姿一致性重打分，取 top-k。这最多是**外观相似度**，不是**任务成功概率**：

- 高相似度的杯子可能在机器人不可达的一侧；
- 高相似度的钩子可能已经被占用；
- 语言里的「左边」「红色」「大杯」可能比外观描述子更可靠；
- 先做一次便宜的观察（换视角、退 2 cm、等一帧）可能比直接抓更划算。

缺一个显式的 `b(h)` 和「看还是做」的决策规则。

### 2.4 一个必须说清楚的边界：官方语言可能很简单

本赛事的 32 个任务大概率使用固定/半固定指令，语言理解本身不是主要矛盾。**本方案的价值不在「解析任意自然语言」，而在「把已知指令编译成可验证合同」**：接地、验证、恢复、截止时间。这个边界决定了 I0 的门槛不应被当成主要创新；如果官方语言确实是固定标签，I0 很容易过，但 I5 仍可能不过——因为收益主要来自验证/恢复，而不是解析。

## 3. 方法：INTENT-BUS

### 3.1 总架构：热路径 / 冷路径

```text
                 ┌──────────────────────────────────────────────┐
                 │ Evaluator: N ports 8765..8765+N-1            │
                 └───────────────┬──────────────────────────────┘
                                 │ websocket: obs / action chunk
                                 ▼
                 ┌──────────────────────────────────────────────┐
                 │ PolicyService adapter (per port)             │
                 │  hot path: state snapshot → arbiter → chunk  │
                 └───────┬───────────────────────────┬──────────┘
                         │ lock-free snapshot         │ async events
                         ▼                            ▼
        ┌────────────────────────────┐   ┌──────────────────────────────┐
        │ Hot: servo + safety +      │   │ Cold: ROS2 / AsyncBus        │
        │      deadline arbiter      │   │  ├ intent compiler           │
        │  (30 Hz, no DDS)           │   │  ├ grounder / belief         │
        └────────────────────────────┘   │  ├ progress / verification   │
                                         │  ├ role-keyed retrieval      │
                                         │  └ VLA action client         │
                                         └──────────────┬───────────────┘
                                                        │ GPU
                                                        ▼
                                         ┌──────────────────────────────┐
                                         │ Shared VLA server (WLA 6B)   │
                                         └──────────────────────────────┘
```

- **热路径不经过 ROS2/DDS**：`get_action` 读取最新状态快照（双缓冲/原子指针），做伺服修正、安全检查和动作仲裁，直接返回。这样 p99 不被中间件调度和序列化拖累。
- **冷路径用 ROS2 或 AsyncBus**：意图编译、接地、进度验证、检索、VLA 请求都是异步的；它们更新共享快照和合同状态，但不阻塞 `get_action`。
- **每端口一个 adapter + 一套合同/信念/缓存**；VLA server 和检索索引只读共享。端口之间用命名空间隔离，`reset()` 通过生命周期服务清空本端口状态。
- **ROS2 是可选后端**：`Bus` 抽象同时有 `Ros2Bus` 和 `AsyncBus`；两者消息 schema 相同。评测容器没有 ROS2 时自动降级，不改变算法。

### 3.2 意图合同：从一句话到一张偏序图

合同定义为

```text
C(ℓ) = (V, E_ord, E_alt, ρ, β_0, Φ, Δ, W)
```

- `V`：目标节点集合；每个节点
  `v = (pre_v, post_v, role_v, ctrl_v, tol_v, ttl_v)`；
  `pre_v` 是前置谓词，`post_v` 是验证谓词，`role_v` 是语义角色（theme / goal / support / instrument / constraint），`ctrl_v ∈ {PBVS, IBVS, HYBRID, CONTACT, TRANSPORT, HOLD}`，`tol_v` 是容差，`ttl_v` 是超时。
- `E_ord`：AND 偏序边（前驱全部验证后才能激活）。
- `E_alt`：OR 恢复边（节点失败时可尝试的替代节点/替代接地）。
- `ρ(v) = (task, phase, role, object_type, relation)`：检索键；这是对第 12 轮 `(task, phase)` 键的升级。
- `β_0`：接地假设的先验。
- `Φ`：硬安全约束（工作空间、速度、夹爪开度、感知 stale、人体接近代理）。
- `Δ(v)`：节点优先级/截止时间。
- `W(v)`：进度权重，来自 rubric/演示统计。

以 `HangCup` 为例：

```text
locate(cup) → grasp(cup) → lift(cup) → locate(hook)
            → align(cup_handle, hook) → hang(cup, hook)
            → release(cup) → verify(hanging)
```

其中：

- `post_grasp`：夹爪闭合 + 杯子随 EE 刚性运动（`r_grasp` 小）；
- `post_align`：杯柄-钩子距离 < 1 cm，轴向误差 < 5°；
- `post_hang`：杯子由钩子支撑，EE 撤离后杯子稳定 ≥ 0.5 s；
- `ctrl_align = HYBRID`，`ctrl_hang = CONTACT`，`ctrl_transport = TRANSPORT`；
- `ρ(align) = (HangCup, ALIGN, theme=cup_handle, goal=hook, relation=hang)`。

以 `PlugInEthernet` 为例：

```text
locate(cable) → grasp(connector) → lift → locate(port)
             → align(connector, port) → insert → verify(seated)
             → release → retreat
```

- `post_insert`：插入深度超过阈值，或松手后线缆仍保持连接；
- `ctrl_insert = CONTACT`，法向缩幅、切向保留；
- `ρ(insert) = (PlugInEthernet, INSERT, theme=connector, goal=port, relation=insert)`。

**合同不是 VLA 的替代品**：VLA 仍产生 30 步动作；合同决定「当前哪个节点激活、伺服目标取哪个角色、验证哪个谓词、失败了走哪条恢复边」。VLA 可以提出动作，合同可以否决/修正/要求重规划，但不能凭空生成语义上不存在的子目标。

### 3.3 意图编译器：受限文法 + 本体 + 回退

编译器输入 `ℓ`，输出 `C(ℓ)` 或 `⊥`（回退 VLA-only）。步骤：

1. **规范化**：中英双语标点/大小写/同义词归一；数字/颜色/方位词入词典。
2. **句法分析**：受限上下文无关文法（Earley，`n ≤ 50`），识别动词框架、从句、时间连词（then / after / 先…再…）、否定/约束。
3. **语义填充**：把动词框架映射到任务模板；槽位填 `theme / goal / support / instrument / manner / constraint`；未填槽位进入歧义集合。
4. **本体校验**：类型/关系/属性必须在本体 `O` 中合法；非法则 `⊥`。
5. **图构造**：按任务模板展开 POGG；多从句按时间连词串接；否定/约束写入 `Φ` 或节点的 `ctrl`（如 "gently" 降增益）。
6. **缓存**：按规范化指令缓存合同；同一指令只编译一次。

如果解析失败或置信度低：回退到**任务级合同**（只有 `locate → act → verify` 三层），或者完全回退 VLA 开环。**解析失败不是执行失败**；它只降低语义分辨率，不阻塞动作。

### 3.4 角色键检索与意图条件化伺服

第 12 轮的 DG-KEYFRAME 检索「受器→夹爪」相对位姿；本轮把检索键从 `(task, phase)` 升级为 `(task, phase, role, object_type, relation)`：

```text
T_base_ee^d(t) = T_base_target(role_v, t) · T_role_ee*(v)
```

- `T_base_target(role_v, t)`：当前帧对 `role_v` 所指实体/站点的位姿估计；
- `T_role_ee*(v)`：从演示库检索到的该角色相对目标；
- 同一个任务的不同节点可以检索不同角色（杯柄 vs 钩子 vs 杯口），而不是共用一个任务级目标。

伺服控制器沿用第 12 轮的 IBVS/PBVS 混合、接触段法向缩幅、延迟补偿；新增两点：

1. **合同一致性检查**：若 VLA 前馈的 EE 速度与「指向当前角色目标」的方向持续相反（`κ_t < 0` 连续 K 块），说明 VLA 计划与合同不一致；降权 VLA 前馈，改用检索轨迹/纯伺服，或触发重规划。
2. **验证驱动的提前切换**：若 `post_v` 已稳定为真（例如人已经把杯子挂上），跳过该节点；若 `post_v` 在接触后突然为假（例如滑脱），回退到 `E_alt` 或重试，而不是继续执行完 chunk。

### 3.5 截止时间感知仲裁器

在每个 `get_action` 时刻，候选动作有四个来源：

- `a_VLA`：plan cache 的 5 步切片；
- `a_servo`：VLA 前馈 ∘ 伺服修正；
- `a_obs`：有界观察动作（换视角/退 1–2 cm/等一个 chunk），只在歧义高且 VOI 足够时；
- `a_hold`：保持当前位姿，永远安全。

定义预算 `B_t`（本次 `get_action` 必须返回的时间余量）、动作延迟 `L(a)`（p95）、风险 `R(a)`、合同进度增益 `ΔP(a)`。仲裁：

```text
a* = argmax_{a ∈ A_feasible} U(a)
U(a) = E[ΔP(a) | b_t, C] - λ_s R(a) - λ_l L(a) - λ_c C(a)
A_feasible = {a : L_p95(a) + ε ≤ B_t, safety_ok(a), contract_version_match(a)}
```

- 若无可行动作 → `a_hold`；若 `a_hold` 也不满足（例如必须保持运动），用降速的缓存 plan。
- `a_obs` 只在 `VOI(q) > c(q) + θ` 且 `B_t` 足够时进入候选；最多每节点一次。
- 仲裁器是确定性的；没有学习权重。它把第 12 轮「异步、可批处理」的工程口号变成可检查的约束。

### 3.6 歧义：信念、VOI、有界观察

接地假设 `h = (γ, ι)`：`γ` 把指称映射到实体集合，`ι` 是解释变体（例如「左边」相对机器人还是相对桌面）。信念：

```text
b_{t+1}(h) ∝ b_t(h) · L(o_t | h) · 1[h 与合同一致]
```

`L(o_t|h)` 由属性匹配、空间关系、分割/位姿置信度组成；如果某个实体被遮挡，似然变平，信念保持多峰。

决策：

```text
VOI(q) = H(b_t) - E_{z∼p(·|q)} H(b_{t+1})
```

- 若 `max_h b(h) ≥ 1-θ_amb`：直接按 MAP 执行（但仍用 `P_success(h)` 加权，避免「最像但不可达」）。
- 若 `max_h b(h) < 1-θ_amb` 且 `VOI(q*) / c(q*) > θ_ig` 且预算允许：执行一次 `a_obs`，更新信念后再决定。
- 否则：按 `argmax_h b(h)·P_success(h)` 提交；在截止时间面前，犹豫也是成本。

**可证明的边界**：VOI 规则对「单步熵 reduction」是 Bayes 最优的；对多步、带执行风险的问题没有最优性保证。我们只声称单步，不声称全局。

### 3.7 意图修复：人改了世界，不要重做整段

第 11 轮的编辑检测给出「机器人动作解释不了的三维残差」；第 12 轮用它触发「停 → 重定位 → 重规划」。本轮把它升级为**合同级修复**：

```text
if edit detected:
    A = {v : role_v 与编辑区域相交}
    for v in A:
        if verify(v, obs):        # 人已经完成了这个子目标
            mark_verified(v); continue
        if pre(v, obs):           # 目标还在，只是位置变了
            unverify(v); re_ground(v); update ρ(v); continue
        else:                     # 目标被拿走/不可达
            mark_blocked(v); try E_alt(v)
    if repairs > R_max: fallback_vla_only()
```

三种结果：

- **人做完了**：跳过，不重做；
- **人移动了**：重新接地，继续；
- **人拿走了/挡住了**：走替代边或安全放弃，不无限追。

这是「意图修复」和「盲目重定位」的区别：修复的对象是**合同节点**，不是整张图；修复的判据是**谓词**，不是外观相似度。

### 3.8 `get_action` 伪代码

```python
def get_action(obs):
    snap = bus.latest_snapshot(obs)          # hot path, no DDS
    C = bus.contract()                       # per-port, versioned
    b = bus.belief()                         # updated by cold path
    prog = bus.progress()                    # active/verified/blocked

    if C is None or C.version != snap.contract_version:
        return adapter.hold_or_cached(snap)

    active = select_active(C, prog, b)
    if active is None:
        return adapter.hold_or_cached(snap)

    if ambiguous(b, active) and deadline_allows_obs(snap):
        q = argmax(VOI(q) for q in OBS_ACTIONS)
        if VOI(q) > cost(q) + THETA_IG:
            return adapter.to_api(obs_action(q), snap)

    a_vla   = plan_cache.slice(H_C) if plan_cache.fresh(snap) else None
    a_servo = servo.compute(snap, active, b)
    a_hold  = hold(snap)

    cands = [a for a in (a_vla, a_servo, a_hold) if a is not None]
    feasible = [a for a in cands if latency_ok(a, snap) and safety_ok(a, snap)]
    if not feasible:
        return adapter.to_api(a_hold, snap)

    a = max(feasible, key=lambda x: utility(x, active, b, snap))
    return adapter.to_api(a, snap)
```

**把语言从 VLA 的条件字符串提升为可验证的偏序目标合同，把 ROS2 从提交接口降级为策略侧截止时间总线，让 5 步伺服只在合同激活的节点上工作——在不新增学习模型的前提下，补上「做什么、做到哪、被打断后做什么」。**

### 1.2 为什么是「意图 + OS + 语言」而不是「再大一点的 VLA」（B 级）

第 12 轮的诊断是「最后 3 厘米开环」。本轮的诊断是：**最后 3 厘米不是纯几何问题，它同时是一个「哪个子目标、算不算完成、被打断后保什么」的问题。** 证据链：

1. **5 类泛化轴里有 3 类直接指向语义/接地**：干扰物要求区分「哪个物体」；位置要求把「同一角色」搬到新位置；人为干扰要求判断「目标是否已被移动/完成」。这三类不是更大的 VLA 能自动解决的，因为它们需要**显式的指称与谓词**。
2. **CHUNK-SERVO 的相位机是手工的**：`INIT/PLAN/SERVO/CONTACT/RECOVER/DONE` 对所有任务共用。插入、挂、叠、拉拉链的接触模式不同，但状态机不知道当前节点类型；它只能靠 `d_t` 阈值，不能用「合同说现在是 align 还是 insert」。
3. **单模型规则堵死了「再加一个 LLM 规划器」**；但没堵死「把语言编译成确定性合同」。合同是规格，不是模型。
4. **N 端口 + 远程 API 让运行时成为算法的一部分**：如果 `get_action` 的 p99 超时，再准的伺服也没有意义。ROS2/DDS 的 QoS、deadline、liveliness、命名空间隔离，正好是把这个运行时说清楚的语言；但必须放在策略侧，不能进热路径。


语义动作 `⟦·⟧` 把句法树映射到框架 `F = (v, θ)`：

- `v ∈ {PUT, INSERT, HANG, STACK, ZIP, UNLOCK, POUR, PICK, PLACE, FOLD, SORT, OPEN, CLOSE, REMOVE, TRANSFER}`；
- `θ` 填 `theme / goal / support / instrument / manner / constraint`；
- 未填槽位进入歧义集合 `Θ_?`；
- 否定/方式副词写入 `Φ` 或 `ctrl_v`（如 "gently" 降增益，`"不要碰"` 加避碰约束）。

**定义 2（可编译性）**。`Compile(ℓ) = C` 当且仅当：

1. `ℓ` 被 `G` 至少解析出一棵语法树；
2. 语义框架通过本体 `O` 的类型/关系/属性校验；
3. 任务模板存在，且所有必填角色可被填或进入歧义集合。

否则 `Compile(ℓ) = ⊥`，回退到任务级合同或 VLA-only。

**复杂度**：Earley 解析 `O(n^3)` 最坏、`O(n^2)` 空间；`n ≤ 50`，可忽略。本体校验 `O(|F|·|O|)`。合同实例化 `O(|V|+|E|)`。同一指令缓存，摊销为 O(1)。

### 2.3 意图合同（POGG）

**定义 3（意图合同）**。

```text
C = (V, E_ord, E_alt, ρ, β_0, Φ, Δ, W)
```

- `V`：有限节点集，每个 `v = (pre_v, post_v, role_v, ctrl_v, tol_v, ttl_v)`；
- `E_ord ⊆ V×V`：AND 偏序边，必须无环；
- `E_alt ⊆ V×V`：OR 恢复边，必须无环，且不得与 `E_ord` 形成环；
- `ρ: V → Task × Phase × Role × Type × Relation`；
- `β_0`：`h` 上的先验；
- `Φ`：硬约束集合；
- `Δ: V → R_{≥0}`：优先级/截止时间；
- `W: V → R_{≥0}`：进度权重。

**定义 4（就绪/验证/完成）**。在观测 `o_t` 与假设 `h` 下：

- `ready(v) ⇔ pre_v(o_t;h)=1` 且 `∀u∈pred_ord(v): u∈G_t`；
- `verified(v) ⇔ post_v(o_t;h) ≥ 1-α_v` 且连续 `k_v` 帧成立（滞回）；
- `done ⇔ ∀v∈V_terminal: v∈G_t` 且 `Φ` 未被违反。

**定义 5（进度/健康/风险）**。

```math
P_t = \frac{\sum_{v\in G_t} w_v}{\sum_{v\in V} w_v},\qquad
H_t = \min_{v\in Active_t} c_t(post_v),\qquad
R_t = 1-\prod_{r\in \mathcal R_t}(1-r)
```

其中 `Active_t` 是当前就绪未验证节点，`\mathcal R_t` 包括安全裕度不足、感知 stale、编辑、stall、低置信度。`P_t` 只在 `G_t` 变化时变；`H_t` 可以下降；`R_t` 触发修复/回退。

**HangCup 合同示例**：

| 节点 | `pre` | `post` | `role` | `ctrl` |
|---|---|---|---|---|
| `locate_cup` | 场景可见 | 杯子 mask/pose 置信 ≥θ | theme=cup | PBVS |
| `grasp_cup` | 杯子可达 | 夹爪闭合 + `r_grasp` 小 | theme=cup | HYBRID |
| `lift_cup` | 已抓 | 杯子随 EE 上升 ≥2 cm | theme=cup | TRANSPORT |
| `locate_hook` | 已抬起 | 钩子 pose 置信 ≥θ | goal=hook | PBVS |
| `align_handle` | 钩子可见 | 柄-钩距离 <1 cm，轴误差 <5° | theme=cup_handle, goal=hook | HYBRID |
| `hang_cup` | 已对准 | 杯子由钩子支撑 | theme=cup, goal=hook | CONTACT |
| `release_cup` | 已挂 | 夹爪张开且杯子稳定 | theme=cup | HOLD |
| `verify_hang` | 已松手 | 0.5 s 内杯子稳定 | theme=cup, goal=hook | HOLD |

**PlugInEthernet 合同示例**：

| 节点 | `pre` | `post` | `role` | `ctrl` |
|---|---|---|---|---|
| `locate_cable` | 场景可见 | 线缆/插头置信 ≥θ | theme=cable | PBVS |

### 2.4 接地信念

**定义 6（接地假设）**。`h = (γ, ι)`：

- `γ: Mentions → 2^E` 把每个指称映射到候选实体集合；
- `ι` 是解释变体（例如「左边」相对机器人 / 相对桌面 / 相对观察者）。

**定义 7（信念更新）**。

```math
b_{t+1}(h) \propto b_t(h)\,L(o_t\mid h)\,\mathbf 1[h\text{ 与 }C\text{ 一致}]
```

`L(o_t|h)` 由三部分组成：

1. 属性匹配（颜色/形状/尺寸/材质）；
2. 空间关系（`on/in/left_of/near` 的几何一致性）；
3. 感知置信度（分割 mask、双目深度、腕部特征 inlier）。

不引入第二个学习模型；属性/关系用本体 + 几何 + 颜色直方图/轮廓。若需要开放词汇，使用同一 VLA checkpoint 的文本/视觉特征（C3），且离线缓存，不增加在线模型。

**定义 8（熵与 VOI）**。

```math
H(b) = -\sum_h b(h)\log b(h),\qquad
VOI(q) = H(b_t) - \mathbb E_{z\sim p(\cdot\mid q)} H(b_{t+1})
```

观察动作 `q ∈ Q_obs`：

- 换一个已有视角（头双目 / 左腕 / 右腕）的 ROI；
- EE 后退 1–2 cm 以解除遮挡，再回到原路径；
- 等一个 chunk，让 VLA/伺服产生新的视角。

**说明**：VOI 的单步最优性在第 5 节证明；多步不保证。

### 2.5 执行作为截止时间约束下的合同满足问题

**定义 9（决策时刻）**。在每个 `get_action` 调用（chunk 边界）`t_k`，系统有：

- 最新状态快照 `o_{t_k}`（可能 stale `δ_k`）；
- 合同 `C`（版本 `ver_C`）；
- 信念 `b_k`；
- 进度 `G_k`；
- 预算 `B_k`。

**定义 10（动作集）**。

```text
A_k = {a_VLA, a_servo, a_obs, a_hold}
```

- `a_VLA`：缓存 plan 的 `H_c` 步切片；
- `a_servo`：`a_ff ∘ exp(Δ)`，`Δ` 由当前激活节点的角色目标计算；
- `a_obs`：有界观察动作；
- `a_hold`：保持当前位姿（零增量），永远安全。

**定义 11（可行/效用/策略）**。

```math
A_k^{feas} = \{a\in A_k : L_{p95}(a)+\varepsilon \le B_k,\ safety(a,o_{t_k})=1,\ ver(a)=ver_C\}
```

```math
U(a) = \mathbb E[\Delta P(a)\mid b_k,C] - \lambda_s R(a) - \lambda_l L(a) - \lambda_c C(a)
```

```math
\pi(o_{t_k},C,b_k,G_k) = \arg\max_{a\in A_k^{feas}} U(a)
```

若 `A_k^{feas}=\emptyset`，返回 `a_hold`；若 `a_hold` 也不可行（例如必须在运动），返回降速缓存 plan。仲裁器是确定性的；`λ` 是离线标定的常数，不是学习策略。

**定义 12（合同一致性）**。

```math
\kappa_t = \frac{\langle v_{ee}(t),\ x_{target}(t)-x_{ee}(t)\rangle}{\|v_{ee}(t)\|\,\|x_{target}(t)-x_{ee}(t)\|}
```

若 `κ_t < 0` 连续 `K` 块，说明 VLA 前馈在远离当前合同目标：降权 `a_VLA`，提高 `a_servo` 权重，或触发重规划。`κ_t` 不是成功率，只是「计划是否还在朝合同目标走」的廉价检查。

### 2.6 评分与不确定性（继承第 12 轮）

```math
S = \frac{1}{32}\sum_{t=1}^{32} p_t,\qquad
p_t = \frac{1}{10}\sum_{j=1}^{10} y_{t,j},\quad y_{t,j}\in\{0,1\}
```

320 trials、`p≈0.25` 时 `SE(S)≈2.42pp`。人为干扰轴 `ΔS_human = 0.2 Δp_h`。这些数字决定了：任何 +1–2pp 的声明都不可信；必须配对 A/B + bootstrap CI。

**重要边界**：`P_t` 是内部合同进度，不是成功率，也不是官方步骤分。第 12 轮已经证伪榜单步骤分；本轮不把 `P_t` 当概率，只用它做调度/诊断。真机成功率必须由单任务通道标定。

## 3. 算法步骤

### 3.1 总架构：热路径 / 冷路径

```text
                    ┌──────────────────────────────────────────────┐
                    │ Evaluator: N ports 8765..8765+N-1            │
                    └───────────────┬──────────────────────────────┘
                                    │ websocket: obs / action chunk
                                    ▼
                    ┌──────────────────────────────────────────────┐
                    │ PolicyService adapter (per port)             │
                    │  hot: snapshot → servo → safety → arbiter    │
                    └───────┬───────────────────────────┬──────────┘
                            │ lock-free snapshot         │ async events
                            ▼                            ▼
           ┌────────────────────────────┐   ┌──────────────────────────────┐
           │ Hot path (30 Hz, no DDS)   │   │ Cold path (ROS2 / AsyncBus)  │
           │  ├ servo (IBVS/PBVS)       │   │  ├ intent compiler           │
           │  ├ safety guard            │   │  ├ grounder / belief         │
           │  └ deadline arbiter        │   │  ├ progress / verification   │
           └────────────────────────────┘   │  ├ role-keyed retrieval      │
                                            │  └ VLA action client         │
                                            └──────────────┬───────────────┘
                                                           │ GPU
                                                           ▼
                                            ┌──────────────────────────────┐
                                            │ Shared VLA server (WLA 6B)   │
                                            └──────────────────────────────┘
```

**为什么热路径不能走 ROS2/DDS**：DDS 的发现、序列化、执行器调度会引入不可控的抖动；`get_action` 是同步调用，p99 直接暴露给 evaluator。热路径只读一个双缓冲快照（原子指针/序列号），做 O(1) 的伺服/安全检查，返回动作。ROS2 只在冷路径做异步协调。

**为什么还需要 ROS2/OS 抽象**：冷路径有 5–6 个异步组件，需要消息契约、QoS、生命周期、命名空间隔离、可观测性；这些正是 ROS2 的强项。用 `Bus` 抽象把 ROS2 隔离在冷路径，既拿到工程能力，又不把 DDS 放进热路径。

### 3.2 意图编译器

```python
def compile_instruction(l, ontology, templates):
    l = normalize(l)                       # 中英标点/大小写/同义词/数字
    parses = earley(G, l)                  # n <= 50
    if not parses:
        return None
    frames = [semantic_action(t) for t in parses]
    frames = [f for f in frames if ontology_ok(f, ontology)]
    if not frames:
        return None
    f = max(frames, key=lambda x: parse_score(x))
    C = instantiate(templates[f.verb], f)
    C = add_constraints(C, f.constraints)  # 否定/方式/安全
    C = add_ordering(C, f.clauses)         # then/after/先...再...
    if not acyclic(C):
        return None
    return cache(C)
```

**步骤说明**：

1. **规范化**：`"plug the ethernet cable into the left port"` → 小写、去停用词、同义词映射；中文 `"把网线插进左边端口"` → 动词 `INSERT`、theme=`cable`、goal=`port`、attribute=`left`。
2. **句法**：Earley 解析；多从句按 `Conn` 分割。
3. **语义**：动词 schema 选择任务模板；槽位填角色；属性/方位词进入 `θ`；未填槽位进入 `Θ_?`。
4. **本体校验**：`INSERT(theme=connector, goal=port)` 合法；`INSERT(theme=cup, goal=hook)` 非法（应走 `HANG`）。
5. **图构造**：模板展开；多从句用 `E_ord` 串接；若两个从句无时间连词，默认按出现顺序。
6. **缓存**：`hash(normalized_l)` → `C`；同一指令只编译一次。

**失败回退**：

- `Compile(ℓ)=⊥` → 任务级合同 `C_task`：`locate → act → verify`，`ρ` 只用任务/phase；
- `C_task` 也失败 → VLA-only，`C=∅`；
- 解析成功但接地置信度低 → 保留多假设，进入 VOI。

### 3.4 角色键检索与意图条件化伺服

**检索索引**：

```text
key(v) = (task_id, phase_id, role, object_type, relation)
```

离线：

```text
for each successful episode:
    for each phase:
        k = keyframe(phase)
        T_base_target = estimate_target(episode, k, role)
        T_base_ee = episode.ee[k]
        T_role_ee = inv(T_base_target) @ T_base_ee
        I_wrist = episode.wrist[k]
```

在线：

```python
def servo_target(v, obs, belief):
    key = rho(v)
    cands = index.filter(task=key.task, phase=key.phase, role=key.role)
    cands = cands.rerank(pose_prior=current_pose_prior(v, obs), top=50)
    topk = cands.topk(descriptor_distance(obs.wrist, key), k=5)
    goal = rerank(topk, pose_consistency, image_quality, belief)
    if goal.confidence < THETA_C:
        return None                  # 回退 VLA / PBVS
    T_target = estimate_target(obs, key, belief)
    T_ee_d = T_target @ goal.T_role_ee
    return T_ee_d
```

**与第 12 轮的区别**：

- 第 12 轮：`(task, phase)` → 一个任务级相对目标；
- 本轮：`(task, phase, role, object_type, relation)` → 每个合同节点一个角色级相对目标；
- 同一个 `HangCup` 的 `grasp` 用「杯身/杯柄」模板，`align` 用「杯柄-钩子」模板，`hang` 用「杯口-钩子」模板；不再共用一个任务级目标。

**伺服**：沿用第 12 轮的 IBVS/PBVS 混合、接触段法向缩幅、延迟补偿。新增合同一致性检查 `κ_t` 和验证驱动的提前切换。

### 3.5 截止时间感知仲裁器

```python
def arbitrate(obs, C, b, G, plan, deadline):
    active = select_active(C, G, b)
    if active is None:
        return hold(obs)

    cands = []
    if plan and plan.version == C.version and plan.fresh(obs):
        cands.append(PlanAction(plan.slice(H_C)))
    st = servo_target(active, obs, b)
    if st is not None:
        cands.append(ServoAction(st, active))
    if ambiguous(b, active) and deadline_allows_obs(obs, deadline):
        q = argmax_voi(b, active, obs)
        if VOI(q) > cost(q) + THETA_IG:
            cands.append(ObsAction(q))
    cands.append(HoldAction(obs))

    feasible = [a for a in cands
                if latency_p95(a) + EPS <= remaining(deadline)
                and safety_ok(a, obs)
                and version_ok(a, C)]
    if not feasible:
        return hold(obs)
    return max(feasible, key=lambda a: utility(a, active, b, obs))
```

**效用细节**：

- `E[ΔP(a)]`：若 `a` 是伺服/计划，按当前节点的 `w_v` 和 `post_v` 置信度估计；若 `a` 是观察，按 VOI 的期望进度折算（观察本身不直接推进，但降低错抓概率）。
- `R(a)`：安全裕度（工作空间/速度/碰撞代理）+ stale 惩罚 + 编辑惩罚。
- `L(a)`：离线标定的 p50/p95；在线用最近 50 次更新。
- `C(a)`：检索/观察/重规划的 CPU/时间成本。

**优先级**：安全 > 合同版本一致 > 截止时间可行 > 效用。若 `a_hold` 与 `a_servo` 效用接近，选 `a_hold`（保守）。

### 3.6 歧义：信念、VOI、有界观察

```python
def ambiguous(b, active, obs):
    if max(b.values()) >= 1 - THETA_AMB:
        return False
    # 角色必须有多个可行实体
    return len(candidates(active, obs)) > 1

def argmax_voi(b, active, obs):
    best, best_v = None, -inf
    for q in OBS_ACTIONS:
        v = entropy(b) - expected_entropy(b, q, obs)
        if v > best_v:
            best, best_v = q, v
    return best
```

**提交规则**：

- 若 `max_h b(h) ≥ 1-θ_amb`：按 `argmax_h b(h)·P_success(h)` 提交；`P_success(h)` 是离线按「任务/角色/候选类型」分桶标定的经验成功率，不是第二个模型；未标定时退化为 1，即纯 MAP。
- 若 `max_h b(h) < 1-θ_amb` 且 `VOI(q*) ≥ c(q*)+θ_ig` 且预算允许：执行 `a_obs`，更新信念，下一 chunk 再提交；
- 否则：按 MAP 提交；记录 `ambiguity_commit` 事件，供离线分析。

**为什么不是「总是先看」**：180 s 预算、chunk 边界、VLA 冷路径都在消耗时间；观察动作可能让目标移出视野或引入新风险。VOI 门槛和「每节点最多一次」是硬约束。

```python
def repair(edit, C, G, obs, b):

    for v in affected:

            if alt is not None:
                activate(alt)
    if repair_count > R_MAX:
        fallback_vla_only()
```

**三种修复结果**：

| 观测 | 判定 | 动作 |
|---|---|---|
| `post_v` 仍真 | 人已完成/未破坏 | 跳过，推进 |
| `pre_v` 真、`post_v` 假 | 目标移动/姿态变 | 重新接地，继续 |
| `pre_v` 假 | 目标被拿走/不可达 | 替代边或安全放弃 |
| 反复编辑 | 人在持续干扰 | 停/等/降速，不追 |

**与第 12 轮的区别**：第 12 轮是「停 → 重定位 → 重规划」；本轮先判断**合同节点**是否已被满足/被破坏，再决定跳过/重做/放弃。修复的对象是语义节点，不是整张图。

### 3.8 `get_action` 伪代码

```python
class IntentBusPolicy:
    def __init__(self, bus, compiler, grounder, progress, retrieval, servo, arbiter):
        self.bus = bus
        self.compiler = compiler
        self.grounder = grounder
        self.progress = progress
        self.retrieval = retrieval
        self.servo = servo
        self.arbiter = arbiter
        self.C = None
        self.plan = None
        self.future = None

    def reset(self):
        self.C = None
        self.plan = None
        self.future = None
        self.bus.reset_port()
        self.grounder.reset()
        self.progress.reset()
        self.retrieval.reset()

    def get_action(self, obs):
        snap = self.bus.snapshot(obs)          # hot path, no DDS
        self._maybe_request_plan(snap)

        if self.C is None:
            return self.bus.adapter.hold(snap)

        if self.C.version != snap.contract_version:
            return self.bus.adapter.hold(snap)

        b = self.bus.belief()
        G = self.bus.progress()
        a = self.arbiter.select(snap, self.C, b, G, self.plan, self.bus.deadline())
        return self.bus.adapter.to_api(a, snap)

    def _maybe_request_plan(self, snap):
        if self.future is not None and not self.future.done():
            return
        if self.future is not None:
            self.plan = self.future.result()
            self.future = None
        if self.plan is None or self.plan.stale(snap) or self.plan.version != self.C.version:
            self.future = self.bus.executor.submit(
                self.bus.vla.predict, copy_snapshot(snap), self.C.version
            )
```

```python
        snap = bus.snapshot()
```

### 3.9 ROS2 图、QoS 与端口隔离

**节点/话题**：

| 名称 | 类型 | 方向 | 频率 | 说明 |
|---|---|---|---|---|
| `/p{i}/intent/contract` | topic | cold → all | 每 episode | 合同版本、POGG、Φ |
| `/p{i}/world/state` | topic | adapter → cold | 30 Hz | 图像/EE/夹爪/lower_body，带时间戳 |
| `/p{i}/grounding/belief` | topic | grounder → progress | 5–10 Hz | `b(h)`、候选实体 |
| `/p{i}/progress` | topic | progress → arbiter | 5–10 Hz | `G_t`、`H_t`、`R_t` |
| `/p{i}/servo/goal` | topic | retrieval → servo | 5–10 Hz | 角色目标、容差、模式 |
| `/p{i}/vla/plan` | action | cold ↔ VLA | 每 1 s | `PlanRequest/Feedback/Result` |
| `/p{i}/chunk/command` | topic | arbiter → adapter | 30 Hz | 最终 chunk、来源、版本 |
| `/p{i}/safety/state` | topic | safety → all | 30 Hz | e-stop、限速、stale、人体代理 |
| `/p{i}/reset` | service | adapter → all | 每 episode | 生命周期重置 |

**QoS**：

| 话题 | Reliability | Durability | Depth | Deadline | Liveliness |
|---|---|---|---|---|---|
| `contract` | reliable | transient_local | 1 | ∞ | automatic |
| `world/state` | best_effort | volatile | 1 | 100 ms | automatic |
| `belief/progress` | reliable | volatile | 1 | 200 ms | automatic |
| `servo/goal` | reliable | volatile | 1 | 50 ms | automatic |
| `chunk/command` | reliable | volatile | 1 | chunk period | automatic |
| `safety/state` | reliable | transient_local | 1 | 50 ms | automatic |

**说明**：DDS/ROS2 的 deadline/liveliness 在不同发行版/中间件上支持程度不同；**算法不依赖 DDS 的 deadline 实现**，Bus 层自己做时间戳/stale 检查。ROS2 的 QoS 只是把契约写清楚；AsyncBus 用同样的字段。

**端口隔离**：

- 每端口命名空间 `/p{i}/...`；固定 `ROS_DOMAIN_ID`；`ROS_LOCALHOST_ONLY=1`；禁用 multicast（如可行）。
- 若 DDS 发现/CPU 争用严重，改用每端口独立 domain ID；代价是更多发现流量。
- `reset()`：发布 `reset` 服务，清空合同/信念/进度/plan cache/编辑状态；只读索引不重置。
- 生命周期：`configure → activate → deactivate → cleanup`；端口故障不影响其他端口。
- 可观测性：记录 `contract_version`、`active_node`、`verified`、`repair_count`、`p99`、`stale_count`、`timeout`；不记录原始图像（体积/隐私）。

## 5. 正确性论证

### 5.1 假设

- **A1（合同可靠性）**：若终端节点全部验证且 `Φ` 未被违反，则按任务本体，指令的目标被满足。A1 是离线模板校验义务，不是线上可证命题。
- **A2（验证单边误差）**：对任意节点 `v`，`P(verify_v=1 | ¬post_v) ≤ δ_v`；`δ_v` 由离线标定给出。
- **A3（伺服稳定）**：在 CHUNK-SERVO 的稳定域内，离散控制律收敛；延迟 `d` 满足 `0<KH_c<` 稳定上界。
- **A4（公平性）**：VLA 冷路径最终返回，或存在缓存 plan；`a_hold` 始终可行。
- **A5（安全）**：`safety_ok` 对每个动作可判定；`a_hold` 满足 `Φ`。
- **A6（修复有界）**：每个节点重试/修复次数 ≤ `r_v`；`E_alt` 无环。

### 5.2 引理与定理

**引理 1（假成功上界）**。在 A2 下，内部验证集合 `G_T` 中至少一个节点实际未完成的概率 ≤ `Σ_{v∈G_T} δ_v`。

*证明*：对每个 `v`，事件 `verify_v=1 ∧ ¬post_v` 的概率 ≤ `δ_v`；并集界。证毕。

**引理 2（进度单调性，分段）**。在没有编辑/失效事件的时间段内，`G_t` 只增不减，`P_t` 单调不减；每次编辑/失效最多使 `P_t` 下降一个节点的权重。修复次数 ≤ `R_max`，因此 `P_t` 的下降次数有界。

*证明*：`G_t` 只在 `verify_v=1` 时加入；只有在 `repair`/`invalidate` 时移除。无事件时不移除。证毕。

**引理 3（无死锁）**。在 A6 下，合同执行不会无限等待：每个节点最多重试 `r_v` 次；失败后走 `E_alt` 或标记 blocked；`E_ord`/`E_alt` 无环；超时 `ttl_v` 强制失败。因此状态转移次数上界为 `Σ_v (r_v+1) + |E_alt|`。

*证明*：每个节点是一个有限状态机；重试计数单调增加；blocked 节点不再被选为 active；DAG 保证不会回到已 blocked 的前驱。证毕。

**引理 4（截止时间活性）**。若 `B_k ≥ L_{p95}(a_hold)+ε`，则 `get_action` 总能在预算内返回一个合法 chunk；冷路径不阻塞热路径。

*证明*：热路径只做 O(1) 操作；`a_hold` 不依赖 VLA/检索；若 `A^{feas}` 为空，返回 hold。证毕。

**引理 5（安全性）**。每个发出的动作满足 `Φ` 或为 hold；若 hold 也不可行，返回降速缓存 plan，且该 plan 在安全包络内。

*证明*：`A^{feas}` 的构造过滤了 `safety_ok=0` 的动作；空集返回 hold；降速 plan 由安全模块限幅。证毕。

**定理 1（有界时间内的合同完成或安全放弃）**。在 A1–A6 下，每个 episode 在 `T_max` 内到达 DONE 或 ABORT；若 DONE，终端谓词以至少 `1-Σδ_v` 的概率成立；所有发出的动作满足 `Φ`。

*证明*：由引理 3，状态转移有限；由引理 4，每个 `get_action` 返回；由引理 5，动作安全；由引理 1，DONE 时假成功概率有界；由 A1，终端谓词成立蕴含任务目标。证毕。

**定理 2（单步 VOI 最优性）**。给定有限假设集 `H`、观察动作 `q` 和似然 `p(z|h,q)`，选择 `q* = argmax_q VOI(q)` 等价于选择使期望后验熵最小的单步观察动作。

*证明*：`VOI(q)=H(b)-E_z H(b')`；`H(b)` 与 `q` 无关，故 `argmax VOI = argmin E_z H(b')`。证毕。

**定理 3（角色键检索的收益是经验命题，不是定理）**。角色键检索是否优于任务/相位键，取决于演示库中角色相对位姿的方差；本报告只把它列为 H2，不声称理论保证。

### 5.3 保证的边界

1. **A1 不是线上可证的**：合同模板可能错；DONE 只表示「合同认为完成」，不表示 evaluator 认为完成。INTENT-BUS 从不覆盖 evaluator 的成功判定，也不提前终止 episode。
2. **A2 在分布漂移下可能失效**：验证阈值需按 shift 轴重新校准；FPR 是离线估计，不是线上保证。
3. **VOI 只保证单步**：多步观察/执行的风险没有最优性。
4. **软实时**：p99 依赖 OS/容器/CPU 争用；ROS2 deadline 是尽力而为，不是硬实时。
5. **合同覆盖有限**：`Compile(ℓ)=⊥` 时回退任务级/VLA；不声称理解任意语言。

| I6 | 全量稳定？ | 32×10 干跑无串扰；内存平；reset 干净；p99 达标 | 回退 CHUNK-SERVO |

### 6.7 统计与可复现

- 配对 A/B：同一初始条件、同一机器人、同一天；差值 `Δ_t`；bootstrap 10k 次。
- 320 trials 的 `SE≈2.42pp`；5 次/任务的 A/B 只用于方向，不用于显著性。
- 离线指标按 session/物体/背景分组划分；相邻帧不跨 split；避免数据泄漏。
- 所有随机种子/版本/配置记录；合同版本与 VLA checkpoint 版本写入日志。

## 7. 已知风险与合规

### 7.1 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| C1 离线标注 | 合同/验证只离线生成标签；线上只有 VLA | 最低 | 保守首选 |
| C2 确定性控制器 | 文法/本体/仲裁/伺服无学习权重；VLA 是唯一学习模型 | 低；需说明 | 主推 |
| C3 同 checkpoint 特征 | 目标/语言描述子用 VLA 同一 checkpoint，不加载第二个模型 | 低–中；需说明 | 需要开放词汇时用 |

**禁止**：加载第二个 LLM/VLM 做在线规划、独立视觉编码器做决策、独立残差策略。

**合规写法**：提交材料明确「intent compiler = deterministic grammar/ontology；retrieval = data index；arbiter/servo = deterministic controller；the only learned model is the official WLA checkpoint」。

### 7.2 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 语言 OOD/解析脆弱 | 合同错误/错目标 | 受限文法 + 本体 + 任务级回退；解析失败不阻塞 |
| 验证假阳性 | 提前跳过/误判完成 | 保守阈值 + 滞回 + 不覆盖 evaluator；验证只做内部调度 |
| 验证假阴性 | 反复重做/超时 | 超时强制前进/回退 VLA；记录事件 |
| 接地失败（遮挡/透明） | 抓错/插错 | 多峰信念；VOI 观察；低置信回退 |
| ROS2 不可用/开销 | 提交失败/p99 超标 | Bus 抽象 + AsyncBus 默认；ROS2 只做冷路径 |
| 冷路径延迟 | 合同/信念过期 | 版本号 + stale 检查；热路径用旧合同但降速 |
| 单模型解释 | 被判第二个模型 | C1/C2/C3；无学习权重；提交说明 |
| VOI 浪费时间 | 180 s 内做不完 | 每节点最多一次；预算不足直接 MAP |
| 人为干扰追目标 | 无限重试 | `R_max` + 替代边 + 安全放弃 |
| N 端口 CPU/DDS 争用 | p99 抖动 | 命名空间；热路径无 DDS；CPU 亲和；只读索引共享 |
| 合同过刚 | 压过 VLA 语义 | 合同只约束角色/谓词/安全；VLA 有不一致检查 |
| 语言其实很简单 | 收益不足 | 先做验证/修复/总线；解析器可选 |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组；相邻帧不跨 split |

### 7.3 Kill switches

1. **I0/I1 一周不过**：退回任务级合同 + 运行时总线；不投真机时间调解析器。
2. **I3 不过**：关闭 ROS2 冷路径，只保留 AsyncBus/热路径；若仍不过，回退 CHUNK-SERVO。
3. **I4 不过**：去掉 VOI/修复，只保留验证驱动的诊断。
4. **I5 不过**：不提交 INTENT-BUS；保留离线分析。
5. **I6 不过**：回退 CHUNK-SERVO 提交。

## 11. 一句话押注

**把语言从 VLA 的条件字符串提升为可验证的偏序目标合同，把 ROS2 从提交接口降级为策略侧截止时间总线，让 5 步伺服只在合同激活的节点上工作——在不新增学习模型的前提下，补上「做什么、做到哪、被打断后做什么」。**

**当前方案最大的风险是：官方语言很可能只是 32 个固定任务标签，意图合同带来的收益不足以抵消它引入的接地/验证/延迟新故障，最后变成一个漂亮但只增加 p99 的语义中间层。**
