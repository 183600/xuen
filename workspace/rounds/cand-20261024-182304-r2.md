# 第 8 轮 · RELAY：把成功率当目标，把 180 秒当预算

> 检索/复核日期：2026-10-24（UTC）。按文件谱系这是第 8 轮；若按用户口径的“本轮第 2 次迭代”，它是第 7 轮 PILOT 的延续而不是重开。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型，选手自部署 + 官方远程真机 API。本轮三个灵感词是「**开源生态**」「**视觉伺服**」「**具身智能大模型**」。

## 0. 先纠正一个比灵感更重要的事实：成功率是主目标，步骤分只是 tie-break

第 7 轮 PILOT 的核心论证是“终局放置约占 60% 步骤分，所以值得重点攻”。这个观察本身没错，但**目标函数读错了**。本轮把参赛手册的排名段重新核对了一遍，原文是：

> “实时榜单按 32 个任务的总平均成功率进行排序，成功率相同时按总平均步骤分排序，若仍相同，则提交日期较早的模型排序靠前。”[S1]

这意味着排名是**字典序**的：`(总平均成功率, 总平均步骤分, 提交日期)`。步骤分只在成功率打平时才起作用。因此：

- **成功率是唯一的主目标**；步骤分是第二目标，不能为了刷步骤分牺牲成功率。
- 第 7 轮“终局放置 ≈ 60% 步骤分”的杠杆论证要降级：终局仍然是**成功闸门**（终局步骤未完成，任务通常判失败；官方评分点把它放在最后 40–50 分），但它值的不是 60% 的排名权重，而是“0 或 1”的通过/不通过。
- 这反而让终局更重要，而不是更不重要：**一个终局失败会让任务不计入成功率**；前面的步骤分只在成功率打平时才有意义。优化目标从“最大化期望步骤分”改成“**最大化任务级成功概率，步骤分只做安全垫**”。

这条修正直接推翻“用步骤分刷榜”的路线，也解释了为什么本届头部模型步骤分能到 39 分、成功率却只有 29.7%：**会做前面的步骤，不等于能把最后一步做成功**。

## 1. 三个灵感词，各自钉到本轮核实到的事实上

### 1.1 开源生态：底座已经商品化，差异化在可靠性层

本轮把“开源生态”具体化为可用的底座、数据和工具，而不是泛泛的“开源很重要”：

- **Unitree UnifoLM-WLA-1.0-Base**：6B，约 2,500 小时真机数据，64 个任务，支持 Dex1 五指手，Apache-2.0；官方开源了冻结 VLM + LoRA + action expert 的微调代码；动作是 54 维统一向量，末端执行器用“相对当前 EE 的 xyz + 旋转向量”，默认 30 步 chunk @30fps。[S8][S10]
- **MolmoAct2**：Ai2 的全开源 action reasoning 模型，Molmo2-ER 骨干 + flow-matching action expert，强调深度/空间推理和低延迟；在多个真实基准上超过 π0.5，且训练/数据/评测 recipe 全开。[S17]
- **WALL-OSS-0.5**：4B VLA，20+ 本体、1M+ 轨迹/epoch，官方强调“deployment-ready”，在 15 个真实任务上比 π0.5 高 17.5%。[S20]
- **DreamZero**：14B World Action Model，视频扩散骨干，7Hz 实时，跨本体泛化约为 SOTA VLA 的 2 倍。[S21]
- **官方数据**：32 个任务、每个 969–1,530 条、合计约 33k 条 / 169 小时、30fps、四路 480×640 相机（head stereo 左右 + wrist 左右）、每任务 5 条英文复述；Apache-2.0，最近更新 2026-10-14。[S13]

结论：**“训一个更强的通用 VLA”已经不是边际收益最高的方向**。头部 8 个模型全是通用基座（MolmoAct2、WALL-OSS、DreamZero、Spirit、DM0、π0.5、GigaBrain-0、GR00T N1.5），其中 MolmoAct2 / WALL-OSS / DreamZero 等已开放权重，开源生态把可用基座推到同一量级；真正的差距在“把基座接到这个 32 任务、10 次/task、5 轴扰动的评测制度上”的**可靠性工程**。

### 1.2 视觉伺服：把“最后一厘米”从生成问题变成控制问题

本轮把“视觉伺服”具体化为“用参考图像/关键帧做闭环”，而不是“再加一个深度相机”：

- **VGM-VS**：用预训练视觉几何模型 + 参考图像做 PBVS，明确针对遮挡、弱纹理、小目标，以及 USB-C / 线缆 / RAM 插入这类亚厘米级任务；用场景特定的度量适配解决尺度歧义。[S22]
- **WARP-VLA**：腕部相机扰动会让 π0.5 的成功率从 78.3% 掉到 39.2%，做扰动适配后恢复；说明腕部视角既是精度来源，也是脆弱点。[S24]
- **FoveaVLA**：用 foveation action 替代腕部相机，77.1% vs 52.1%；**Fisheye-VLA** 讨论相机覆盖 vs 分辨率的取舍。[S25][S26]
- **VLaRL / PathTime-VLA**：冻结 VLA + 残差 RL / 路径-时间解耦，专攻接触丰富和精密插入；UniBot 接口没有力反馈，力反馈路线不能直接照搬。[S23][S32]

结论：**VLA 擅长“去哪里”，不擅长“最后一毫米怎么对准”**。官方 33k 成功演示里恰好有大量“最后一厘米”的终局帧：它们可以作为视觉伺服的参考图像库，而不需要额外采数据。这是“开源生态 + 视觉伺服”最自然的结合点。

### 1.3 具身智能大模型：语义先验已经够用，执行可靠性不够

本轮把“具身智能大模型”具体化为“基座能提供什么、不能提供什么”：

- 头部模型在 32 任务上的**占位**成功率是 29.7% / 28.5% / 27.9% / 25.9% / 23.5% / 22.8% / 22.6% / 20.5%，步骤分却仍有 28.1–39.0；成功率与步骤分的平均差约 **8.6 个百分点**。[S4]
- 320 次计分 trial 下，单个模型成功率的二项标准误约 **2.56pp**；top 3 之间只差 1.2–1.8pp，**在噪声内**。要在统计上稳，真实提升需要 **+10pp 量级**（独立双样本、单侧 α=0.05 时，+10pp 的 power 约 85%，+8pp 约 69%，+5pp 只有约 39%）。[S4]
- 官方目标是“ChatGPT moment：80% success on 80% unseen tasks”；当前不到 30%，差距不是“再多喂一点语义数据”，而是**长程执行中的误差累积、接触精度、扰动恢复**。[S16]

结论：**把大模型当“提议器”，不要当“端到端控制器”**。基座负责语义、任务分解和粗动作；最后一厘米、成功判定、失败恢复交给闭环控制层。这是本轮的主判断。

## 2. 本轮主判断：成功率优先的可靠性包络（Reliability Envelope）

一句话：**VLA proposes, servo disposes, critic verifies, budget allocates.**

把单次 30% 的 VLA 包在一个四层“可靠性包络”里：

1. **慢规划层**：开源 VLA（首选 WLA-1.0-Base，备选 MolmoAct2 / WALL-OSS）输出 30 步相对 EE 计划；负责“看懂任务、找到物体、粗定位”。
2. **快伺服层（DAVS）**：在接近/插入/堆叠/拉拉链/拔网线等精密阶段，从官方成功演示中检索最接近的终局关键帧，用腕部 + 头部图像估计相对位姿/特征误差，输出短程 Cartesian 修正；负责“最后一厘米”。
3. **验证层（Critic）**：用几何谓词 + 轻量学习头估计当前步骤完成度、任务成功概率、失败风险；评测 API 不提供 reward，所以必须自己判；负责“现在到底成没成、要不要退”。
4. **预算层（Budgeted Retry）**：把 180 秒当成预算，按可重试性分类、按剩余时间/尝试次数/ critic 置信度决定 continue / settle-verify / micro-retry / macro-retry / abort；负责“失败之后怎么办”。

这四层里，**DAVS 和 Budgeted Retry 是研究火力**，慢规划层是开源基座的工程集成，Critic 是让重试可控的安全带。三者缺一不可：没有 DAVS，重试只是重复同一个错误；没有 Critic，重试会毁掉已经成功的场景；没有预算，重试会烧完 180 秒。

### 2.1 为什么不是“再训一个更大的 VLA”

- 可用基座已经开源且同质化；头部 8 个模型的差距在噪声内，继续卷基座是低胜率赌注。
- 32 任务 × 约 1k 条演示，足以微调动作专家，但不足以从零训练一个能覆盖 5 轴扰动的通用模型。
- 计分 trial 只有 320 次；任何需要“大规模试错”的方法都没有样本效率。
- 相反，**重用官方成功演示做参考库**、**用 180 秒做重试**，都是把评测制度本身变成资源。

### 2.2 为什么不是“只做视觉伺服”

- 纯视觉伺服需要可靠的目标检测/分割/位姿，面对未见物体、背景变化、人干扰会崩；它适合“最后一厘米”，不适合“从零找到任务相关物体”。
- 纯 IBVS 在遮挡、弱纹理、尺度变化下不稳定；需要 VLA 的语义先验来选参考帧、选特征、选何时切入伺服。
- 所以是 **VLA 提议 + 伺服收尾**，不是二选一。

## 3. 与第 7 轮 PILOT 的关系：保留、升级、合并、修剪

用户要求“每轮优先深化与修剪，而不是推倒重来”。本轮对 PILOT 的处置如下：

| 第 7 轮组件 | 本轮处置 | 理由 |
|---|---|---|
| SSG（评分步骤图门控） | **保留并升级** | 步骤图仍是任务分解和失败定位的骨架；但从“刷步骤分”改为“成功率闸门 + 重试触发点” |
| OPT（少样本放置位姿迁移） | **合并进 DAVS** | 单次位姿迁移不够，改成“检索参考帧 + 闭环伺服”的连续修正 |
| PGL（视觉锚点） | **保留为回退** | 当 DAVS 置信度低时，用锚点做粗定位；不单独作为主线 |
| SVL（settle-verify） | **升级为 Critic 门控** | 原来只在终局“停一下再看”；现在贯穿每个步骤，并输出成功/失败概率 |
| NRB（官方备注恢复） | **保留并扩展** | `generalization` 的 human_1/human_4/unseen_object_3 备注是官方给的“扰动剧本”，直接变成恢复策略库 |
| ICR（检索增强） | **合并进 DAVS 参考库** | 检索不再只是“找相似轨迹”，而是“找伺服参考帧” |
| L2L（语言到语言/跨任务语言迁移） | **降级** | 5 条英文复述已经给出，语言多样性不是当前瓶颈；保留 canonicalization 即可 |
| FLEET（部署工程） | **降为检查单** | 端口、reset、延迟、日志仍然重要，但不占用研究主线 |
| “终局放置 ≈ 60% 步骤分” | **修正** | 终局是成功闸门，不是排名权重；目标函数改为成功率优先 |

**被本轮淘汰的叙事**： “只要把终局放置做好，就能同时拿成功率和步骤分”。正确表述是： “终局是成功闸门；先把成功率做上去，步骤分只在打平时帮忙”。这避免了为了 40 分而在已经成功的场景里继续动、反而把成功弄丢。

## 4. 新分析：32 个任务不是同一种“可重试性”

重试是本轮最大的杠杆，但**不是所有任务都能重试**。本轮按“失败后场景是否可恢复”把 32 个任务粗分为三类（这是我们的工程分类，不是官方分类）：

- **R0 可安全重试（约 20 个）**：抓取/放置/堆叠/排列/收纳类。失败通常只是没抓住、没对准、没放稳，物体还在桌面，可以退回安全位再试。例：T02 水果入篮、T04 水果分盘、T06 积木排列、T10 插插头、T19 拉拉链、T26 插网线、T27 叠碗、T31 文具袋。
- **R1 需谨慎重试（约 9 个）**：失败可能让物体掉落/滚动/卡住，或让人工道具状态变化。例：T01 挂杯（杯子可能掉）、T03 装娃娃（袋子可能倒）、T08 上书架（书可能掉）、T09 工具入箱并上锁（锁/工具可能卡）、T11 挑电池（电池可能滚）、T12 开锁（钥匙可能卡）、T13 摆试管（试管可能倒）、T21 摆盘子（盘子可能掉）、T30 拔图钉便签（便签可能撕）。
- **R2 不应盲目重试（3 个）**：**T14 倒药**（药倒出来就回不去）、**T24 传送带分拣**（目标在动，错过就没了）、**T32 针管移水**（水洒了就不可逆）。这三个要用“预防性伺服 + 一次做对”，而不是“失败再试”。

这个分类直接决定预算分配：R0 允许 2–3 次尝试；R1 只允许 1 次“微重试”，且必须先退回安全位；R2 不重试，把时间花在接近阶段的低速/多视角确认。**“重试”不是无脑循环，而是按任务可逆性分配的风险预算。**

## 5. 关键假设与可证伪点

本轮的主判断建立在五个可检验假设上。产物区会给出对应实验；这里先写清楚“什么结果会杀死它”：

- **H1（失败集中）**：占位榜的成功率-步骤分差主要来自每任务的最后一个 40–50 分步骤（少数任务为 25 分），而不是前面的抓取/搬运。若真机失败分布不是这样，DAVS 的收益会下降。
- **H2（伺服有效）**：在最后 1–3 厘米，参考帧 + 腕部图像的闭环修正能把该步骤成功率提高至少 10pp；若提高 <5pp，DAVS 不值得作为主线。
- **H3（重试可叠加）**：在 R0 任务上，第二次尝试的成功率不低于第一次的 60%（即失败不是完全相关的）；若第二次几乎必败，重试预算应全部转给 DAVS/预防性伺服。
- **H4（Critic 可校准）**：不依赖评测 reward，仅用视觉 + 本体状态，就能把“成功/失败”判到 AUROC ≥0.85，且假成功（false success）率 <5%；否则重试会毁掉成功场景。
- **H5（基座够用）**：WLA-1.0-Base 在官方 32 任务上微调后，单次成功率能到 25–30% 量级；若基座微调后连 20% 都不到，先修基座，不谈包络。

## 6. 风险、合规与“别把自己玩死”

- **单模型边界**：官方要求“一个模型完成全部任务”。我们的设计是**一个 checkpoint**（VLA + 辅助头），DAVS 是确定性代码，参考库是官方数据；所有辅助模块在模型卡中披露。若官方认定“辅助头/检索库”算第二个模型，退化为“只保留 VLA + 确定性伺服”，不牺牲主线。
- **外部数据/预训练权重**：手册只渲染到 §2.2，外部数据是否允许尚未核实；本轮默认**只用官方 33k + 开源基座**，不引入自采数据。若允许外部数据，再考虑加实验室数据。
- **重试的副作用**：可能把物体推下桌、把已成功的拉链拉开、让人工干扰后的场景更糟。用 R0/R1/R2 分类 + Critic 假成功率门限 + “成功即保持”来约束。
- **评测停止条件**：手册写的是“直至任务成功、失败或超时”，倾向成功即停；但 API 层是否立刻停止调用未在 README 写明。产物区仍把“成功保持”作为防御性硬约束。
- **动作 chunk 固定**：`action_chunk_size` 是提交元数据；如果评测固定按该长度开环执行，快伺服只能用短 chunk（4/8）实现。产物区给出 chunk=1/4/8/30 的延迟-精度权衡与降级方案。
- **统计噪声**：320 次 trial 的排名噪声很大；不要把 1–2pp 的波动当真实提升，也不要在一次 debug 运行后就改主线。产物区给出预注册的分析计划。

## 7. 本轮一句话押注

**把 180 秒当预算、把失败当可恢复状态：以开源 VLA 为提议器，用官方演示锚定的视觉伺服（DAVS）收最后一厘米，用校准 critic 驱动预算化重试——这是把 <30% 推到 45%+ 的最短路径，也是本轮最值得押注的方向。**

## 1. 目标函数：成功率字典序，统计门槛 +10pp

### 1.1 规则到目标

官方手册的排名规则是“总平均成功率 → 总平均步骤分 → 提交日期”[S1]。形式化：

```
maximize  ( mean_i success_i ,  mean_i step_score_i ,  -submit_date )
```

其中 `i` 是 32 个任务，每个任务 10 次 trial；`success_i ∈ {0,1}`。步骤分只在成功率完全相同时才参与比较。因此：

- 任何“提高步骤分但可能降低成功率”的动作，默认不做。
- 终局步骤是成功闸门：从任务语义和评分点看，终局未完成通常 `success=0`；只完成前面步骤只拿步骤分。官方未逐任务写明“必须全步骤”，这是待 E0 确认的假设。
- 重试的收益按“是否把 0 变成 1”计算，不按“多拿 40 分”计算；但重试不能把已经 1 的场景变回 0。

### 1.3 320 次 trial 的统计门槛

每个模型 32×10=320 次 trial。单模型成功率的二项标准误：

```
SE = sqrt(p(1-p)/n) ≈ sqrt(0.3×0.7/320) ≈ 2.56pp
```

两个独立模型差值的标准误约 `sqrt(2)×2.56 ≈ 3.6pp`；top 3 之间 1.2–1.8pp 的差距在噪声内。独立双样本、单侧 α=0.05 的 power：

| 真实提升 d | power（独立，n=320/组） | 解读 |
|---:|---:|---|
| +3pp | 约 20% | 基本测不出来 |
| +5pp | 约 39% | 不可靠 |
| +8pp | 约 69% | 仍不够稳 |
| +10pp | 约 85% | 可接受的最低目标 |
| +12pp | 约 94% | 比较稳 |

注意：32 个任务簇内的 10 次 trial 可能相关，实际有效样本更小、power 更低；上表是乐观上界。**结论：不要为 1–2pp 的架构改动下注；本轮所有实验以 +10pp 为 go/no-go 门槛，分析用按任务配对的 bootstrap。**

## 2. 系统架构与状态机

### 2.1 单 checkpoint 边界

为满足“一个模型完成全部任务”：

- **一个 checkpoint**：VLA 主干 + 动作专家 + 辅助头（phase / success / time-to-go / risk）。
- **确定性代码**：步骤图、DAVS 几何解算、预算控制器；不引入第二个策略网络。
- **数据**：官方 33k 演示构建的参考库；不含外部数据。
- **披露**：模型卡写明辅助头、参考库、确定性伺服、预训练感知工具（若运行时使用）。

如果官方认定“辅助头/参考库”算第二个模型，降级为“VLA + 确定性 DAVS + 规则重试”，主线不变。

### 2.2 状态机

```
RESET
  → APPROACH（VLA 粗定位/接近）
  → ALIGN（DAVS 低速对准，短 chunk）
  → SERVO（DAVS 闭环，力/视觉误差收敛）
  → VERIFY（Critic 多帧确认）
      ├─ success → HOLD（保持，直到评测停止）
      ├─ uncertain → VERIFY_AGAIN（最多 2 次）
      └─ failure → RETRY_DECISION
            ├─ micro-retry（退回 1–3cm，重对准）
            ├─ macro-retry（回安全位，重做该步）
            └─ abort/advance（R2 任务或预算不足）
```

### 2.3 单次调用时间预算

评测按 `action_chunk_size` 开环执行；若 chunk=4 @30fps，一次调用的预算约 133ms。目标分解：

| 环节 | 目标耗时 | 备注 |
|---|---:|---|
| 网络 RTT + 图像解码 | 20–50ms | 4 路 480×640；可只解码 wrist/head 两路 |
| VLA 推理 | 200–500ms | 6B，FP16/BF16；用计划缓存摊薄 |
| DAVS 特征/解算 | 5–20ms | 轻量匹配；重模型离线 |
| Critic | 5–20ms | 辅助头/规则谓词 |
| 序列化/排队 | 5–10ms | 预留抖动 |

若 VLA 单次 >133ms，不能每个 chunk 都跑；用 §7 的 plan-cache：VLA 每 K 个 chunk 跑一次，DAVS 在每个 chunk 内修正。若 VLA 500ms，K=4（16 步≈533ms），中间 3 个 chunk 用缓存计划 + 伺服。

### 3.2 动作空间映射

WLA 的统一动作是 54 维，末端执行器是“相对当前 EE 的 xyz + 旋转向量”，默认 30 步 chunk @30fps[S10]。本赛 API 的 EE 动作是 `left/right_ee_pose_gripper_base[6]`（xyz+rpy）+ gripper[S7]。适配层：

```python
# WLA 54-dim -> API EE command
# left: [0:3] xyz, [3:6] rotvec, [6] gripper
# right: [13:16] xyz, [16:19] rotvec, [19] gripper
def wla_to_api(a, T_cur_left, T_cur_right):
    dT_l = se3_exp(a[0:6])          # relative EE
    dT_r = se3_exp(a[13:19])
    T_l = T_cur_left @ dT_l
    T_r = T_cur_right @ dT_r
    return {
        "left_ee_pose_gripper_base":  [*T_l.translation, *rotmat_to_rpy(T_l.rotation)],
        "right_ee_pose_gripper_base": [*T_r.translation, *rotmat_to_rpy(T_r.rotation)],
        "left_gripper": float(a[6]),
        "right_gripper": float(a[19]),
    }
```

**待核实**：API 的 `ee_pose` 是绝对目标位姿还是相对 delta。README 写的是“末端位姿 xyz+rpy”，倾向绝对；若服务端按 delta 解释，适配层切换到直接输出 `a[0:6]`。用 debug 通道的第一步动作验证（发送 +1cm 的 x，观察 EE 是否移动约 1cm）。这是 E0 的必做项。

## 4. DAVS：Demo-Anchored Visual Servoing

### 4.1 定义

**DAVS = 从官方成功演示中检索“当前阶段最接近的终局/关键帧”，用当前腕部/头部图像与参考图像的几何误差，生成短程 EE 修正，闭环执行。** 参考图像伺服的有效性已有 VGM-VS/WARP-VLA 等证据[S22][S24]。

它不是“模仿一整条轨迹”，而是“在最后一厘米，把参考帧当成视觉目标”。参考帧来自 33k 条成功演示，不需要外部数据；检索和几何解算都是确定性的，不引入第二个策略模型。

### 4.2 参考库 schema

```text
ReferenceFrame:
  task_id: T10
  phase_id: 2                  # 对应 score_steps 的索引
  demo_id: episode_0042
  t: 2.13s
  cameras: {head_l, head_r, wrist_l, wrist_r}   # 图像路径/哈希
  ee_pose_l, ee_pose_r: SE(3)  # base 系
  gripper_l, gripper_r: float
  features:
    dino: float[768]           # 离线 DINOv2/CLIP
    orb: keypoints/descriptors # 离线
    mask: RLE                  # 离线 SAM2/颜色分割
    depth: optional            # 离线 DepthAnything
```

构建：

1. 按 `score_steps` 把每条演示切成 2–5 个阶段；边界用“动作停顿/夹爪开合/物体接触”启发式 + 人工抽检。
2. 每个阶段取：进入帧、接触前 5 帧、接触帧、阶段完成帧、最终帧。
3. 每 5 帧抽一个关键帧，保留腕部与头部；用离线模型提特征；存库。
4. 去重：同一阶段/位姿附近只留 3–5 个代表帧，避免检索退化。

### 4.3 检索

```python
def retrieve(task_id, phase_id, obs):
    cands = bank.filter(task=task_id, phase=phase_id)
    # 1) 位姿门控：当前 EE 与参考 EE 的距离/角度
    cands = [c for c in cands if pose_dist(obs.ee, c.ee) < 0.10]
    # 2) 视觉相似度
    q = dino(obs.wrist_l or obs.head_l)
    score = 0.6 * cosine(q, c.dino) + 0.3 * pose_score + 0.1 * phase_score
    return top_k(cands, score, k=3)
```

若没有候选（未见物体/背景变化），退回 PGL 粗锚点或纯 VLA；不要强行伺服。

### 4.4 伺服误差与更新

**IBVS（特征点）**：取参考帧与当前帧的匹配点 `(u_i, v_i) ↔ (u_i*, v_i*)`，误差 `e = s - s*`。单点交互矩阵（`f` 为焦距，`z` 为深度）：

```
L(u,v) = [[-f/z,   0,   u/z,      u*v/f,  -(f + u^2/f),  v],
          [   0, -f/z,   v/z,  (f + v^2/f),      -u*v/f, -u]]
```

堆叠所有点得 `L_e`，阻尼最小二乘：

```
v_c = -λ (L_e^T L_e + μI)^{-1} L_e^T e
```

其中 `v_c = [vx, vy, vz, ωx, ωy, ωz]` 是相机系速度；通过相机-EE 外参/手眼标定转到 EE delta。`λ` 约 0.3–1.0，`μ` 约 1e-3–1e-2；每步限幅 `||Δp|| ≤ 5mm`、`||Δθ|| ≤ 2°`。

**深度来源**：`head_stereo_left/right` 可做双目深度；`wrist_left/right` 只有 RGB，优先 IBVS 或离线标定的单目深度。没有可靠深度时不要硬上 PBVS。

**PBVS（位姿）**：从匹配点 + 深度/PnP 估计 `T_ref^cur`，误差 twist：

```
T_err = T_ref^{-1} @ T_cur
ξ = log_SE3(T_err)          # 6 维
v = -λ ξ
```

将 `v` 转到 EE 系，得到 `Δp, Δθ`；同样限幅。弱纹理时用轮廓/椭圆特征做 IBVS，或改用 PBVS；有可靠深度/已知物体几何时 PBVS 更直接。

**融合**：内部统一用“相对当前 EE 的 delta”，避免绝对/相对混用；最后由 §3.2 适配层转成 API 需要的绝对位姿。

```
a_vla   = [Δp_vla, Δθ_vla, g_vla]
a_servo = [Δp_s,   Δθ_s,   g_hold]
a = [(1-α)Δp_vla + αΔp_s,
     (1-α)Δθ_vla + αΔθ_s,
     g_vla]
α = α_max * confidence * phase_gate
α_max = 0.8
```

- `confidence = 1[inliers ≥ 20] * exp(-reproj_err / 2) * temporal_consistency`
- `phase_gate`：只在 ALIGN/SERVO 阶段 >0；APPROACH 阶段 α=0。
- 若连续 3 个 tick 误差不降或 confidence <0.3，退出伺服，回 VLA/PGL。

```python
    if conf < 0.3:
        return None, 0.0
    if has_depth(obs, cam):
        dpose = pbvs(matches, obs.depth[cam], ref.pose)
    else:
        dpose = ibvs(matches, obs.camera_intrinsics[cam])
    dpose = clamp(dpose, max_p=0.005, max_r=math.radians(2))
    alpha = 0.8 * conf * phase_gate(phase)
    return dpose, alpha
```

### 4.7 失败模式与缓解

- **遮挡**：人/工具挡住腕部 → 切头部相机；两路都低置信 → 退回 VLA/PGL。
- **弱纹理**：白碗/白插头 → 用轮廓/椭圆/深度，不依赖角点；有可靠深度时 PBVS，否则轮廓 IBVS。
- **尺度/反光**：参考帧与当前帧尺度差 → 用双目/深度归一化；避免纯像素阈值。
- **参考帧不匹配**：未见物体/背景变化 → 检索分数低就放弃，不要硬伺服。
- **手眼标定误差**：DAVS 的 `Δp` 在 EE 系，标定误差会直接变成偏差；用 debug 通道做一次 1cm/1° 的标定校验。
- **单模型合规**：DAVS 是确定性代码；若运行时用 DINO/SAM/Depth，模型卡披露，必要时改为离线特征 + 轻量匹配。

## 5. Critic：没有 reward，也要知道“成没成”

### 5.1 为什么必须有

评测 API 只给 observation，没有 reward/success 标志。手册说评测会“直至任务成功、失败或超时”，所以成功时大概率会停；但“失败”可能是超时或外部判定，不会作为即时信号传给策略。策略仍必须自己判断：

- 失败了要重试吗？——需要触发，否则 180 秒只做一次。
- 重试会破坏场景吗？——需要风险估计。
- 如果 API 在成功后仍继续调用，要不要 HOLD？——要，否则可能把拉链拉开、把碗碰倒。

### 5.2 三路信号

1. **几何谓词（确定性，可解释）**：每个 score step 写 1–3 个视觉/本体谓词；优先用颜色/深度/夹爪状态，SAM2/DepthAnything 等重模型只用于离线建库/标注，避免运行时第二个策略模型。
   - 抓取：夹爪开度 < 物体宽度 + margin；物体 mask 在夹爪之间；接触阴影/深度差。
   - 插入：插头尖端在插座 bbox 内；轴向角 < 5°；无可见间隙。
   - 叠放：碗沿椭圆中心对齐；竖直间隙 < 2cm；倾角 < 5°。
   - 拉拉链：拉链头到缝线横向误差 < 5mm；齿列闭合；缝线长度减少。
   - 开锁：钥匙转角到位；锁梁开口。
   - 挂杯：杯柄在钩点上方；重力方向对齐。
2. **学习头（辅助头）**：输入 VLA 隐状态 + 图像 embedding + proprio；输出 `p_success`、`p_phase`、`time_to_go`、`p_risk`。2 层 MLP，参数量 <1M，和主模型一起保存。
3. **时间/动作一致性**：动作停滞、误差震荡、阶段超时、重复同一动作 → 失败风险上升。

### 5.3 标签

- **正例**：每条成功演示的最后 10–30 帧（最终状态）；阶段完成帧。
- **负例**：同一演示的早期帧作为“非成功”负例（不是“失败”负例）；扰动增强帧（颜色/遮挡/腕部偏移）；debug 通道的真实失败帧。
- **phase 标签**：官方数据没有 subtask 标签（已核对 features）；用 `score_steps` + 时间分位 + 视觉谓词生成弱标签，再人工抽检 200 帧。不要宣称“官方 phase 标注”。
- **time-to-go**：从演示时间戳回归；只作为辅助信号，不作为唯一监督。
- **成功标签**：任务级 success 由评测判定；debug 通道可人工/规则标注；离线用最终帧正例。

### 5.4 校准与决策

```python
p = sigmoid(w @ [p_head, geo_feat, temporal_feat] + b)
# 温度缩放 + conformal 校准
if p > 0.99 and stable_for(3):
    return "success"      # 高精度，避免假成功
if p < 0.10 and no_progress_for(5):
    return "failure"      # 高召回，触发重试
return "uncertain"
```

成本矩阵：假成功（把失败当成功，停止/继续破坏）代价最高；假失败（把成功当失败，重试）次之。因此 success 阈值取高精度（目标假成功率 <5%），failure 阈值取高召回；不确定时多验证 2 帧，不急着重试。

指标：AUROC ≥0.85；ECE <0.05；FPR@TPR95 <10%；**假成功率 <5%**（E2 验收）。

### 5.5 伪代码

```python
def verify(obs, phase, history):
    geo = geometric_predicates(obs, phase)
    head = critic_head(obs.vla_feat, obs.img_feat, obs.proprio)
    temporal = temporal_consistency(history)
    p = calibrate(head, geo, temporal)
    if p > 0.99 and stable(history, n=3):
        return "success", p
    if p < 0.10 and no_progress(history, n=5):
        return "failure", p
    return "uncertain", p
```

## 6. Budgeted Retry：把 180 秒当预算

### 6.1 形式化

状态 `s = (phase, attempt, t_remaining, p_success, risk, retry_class)`；动作：

- `continue`：继续当前计划；
- `verify`：停下来多看几帧；
- `micro_retry`：退回 1–3cm，重对准；
- `macro_retry`：回安全位，重做当前步骤；
- `abort`：放弃当前步骤/任务，保留步骤分。

有限时域 MDP：

```
V_t(s) = max {
  V_continue(s),
  V_verify(s),
  -c_retry + p_recover * V_{t+1}(s') + (1-p_recover) * V_{t+1}(s_fail),
  V_abort(s)
}
```

终局奖励：`success = 1`；步骤分只给 `ε = 0.01` 的 tie-break 权重；场景损坏 `-0.5`；时间成本很小（避免无意义拖延）。因为成功率是字典序第一，`ε << 1`，重试决策不会被步骤分带偏。

这个预算模型假设**一次 trial 内策略可以继续动作到 180s**；若评测在首次失败时立即 reset，则“重试”只能在同一个 180s 窗口内完成，或退化为跨 trial 的预热/自适应。E0 必须确认 reset 语义，否则 §6.3 的收益上界不成立。

### 6.3 重试收益（模型推算，不是实测）

FLARE/FAR/CycleVLA 等已报告 failure-aware retry/reset 的收益[S27][S28][S29]；下面只算本赛 180s 预算下的上界。单次成功率 `p=0.30`，最多 `k` 次，失败可恢复且重试独立；**下表 `k` 为总尝试次数（含第一次）**：

| k | 成功概率 | 相对单次 |
|---:|---:|---:|
| 1 | 30.0% | — |
| 2 | 51.0% | +21.0pp |
| 3 | 65.7% | +35.7pp |
| 4 | 76.0% | +46.0pp |

| k | 成功概率 | 相对单次 |
|---:|---:|---:|
| 2 | 42.7% | +12.7pp |
| 3 | 49.8% | +19.8pp |
| 4 | 55.3% | +25.3pp |

### 6.4 时间预算

官方总时长 169h / 约 33k episodes ≈ **18.4s/episode**；轻任务 HangCup 6.2s，ZipUp 14.1s。180s 上限：

```
180 / 18.4 ≈ 9.8 次理想尝试
考虑 VLA 推理、退回、验证开销（×1.5–2）→ 5–6 次
保守按 3–4 次设计
```

分配：`t_reserve=30s` 给最终验证/保持；`t_attempt` 按任务演示时长 P90 估计；R0 允许 3 次，R1 允许 1 次 micro-retry，R2 不重试。若剩余时间 < 1.5×P90，停止重试，进入“保步骤分”模式。

### 6.5 安全重试

- **安全位**：每个任务预定义 1–2 个 retreat pose（EE 高于桌面 10–15cm，夹爪张开），从演示统计得到；重试前先回安全位。
- **场景检查**：重试前用 Critic/几何谓词确认物体还在桌面、没有被推到边缘；若 risk 高，不重试。
- **两振出局**：同一阶段连续 2 次失败，第三次只做“预防性低速对准”，不再大力重试。
- **成功后保持**：Critic 判 success 后，输出保持动作，禁止继续计划。
- **最大尝试数**：R0=3，R1=2（含 micro），R2=1；硬上限 5，防止烧预算。

### 6.6 伪代码

```python
def retry_decision(obs, phase, hist, budget):
    p, conf = critic(obs, phase, hist)
    if p > 0.99:
        return "hold"
    if budget.remaining < budget.reserve + budget.est_attempt(phase):
        return "abort"
    if p < 0.10 and hist.no_progress >= 5:
        if retry_class[obs.task] == "R2":
            return "abort"
        if hist.attempts >= max_attempts[obs.task]:
            return "abort"
        if risk_high(obs):
            return "abort"
        return "macro_retry" if hist.attempts >= 1 else "micro_retry"
    return "continue"
```

## 7. 双频 Plan-Cache + Servo：让慢 VLA 接上快伺服

### 7.1 问题

- VLA 6B 单次 200–500ms；30Hz 控制要求 33ms。
- 评测按 chunk 开环执行；chunk=30 意味着 1 秒内没有反馈，DAVS 无法工作。
- 直接 chunk=1 会让 VLA 每步都跑，延迟爆炸。

### 7.2 设计

- 提交 `action_chunk_size=4`（7.5Hz 反馈）或 `8`（3.75Hz）；优先 4。
- **慢计划**：VLA 每 K 个 chunk 跑一次，输出 30 步计划；K=4–8。
- **快伺服**：每个 chunk 取计划的下 4 步，叠加 DAVS 修正，输出 4 步。
- **预取**：在后台线程跑下一次 VLA；若未就绪，用当前计划外推/保持，不阻塞。
- **相位切换**：进入 ALIGN/SERVO 时强制刷新计划；离开时恢复。
- **降级**：若评测只接受 chunk=30，DAVS 无法在 30 步内闭环，只能退化为“计划生成时修正 + 早停”；这种情况下伺服层失效，必须优先确认 chunk 可设为 4/8。

### 7.3 伪代码

```python
class RelayPolicy:
    def __init__(self):
        self.plan = None
        self.plan_age = 0
        self.phase = "APPROACH"
    def get_action(self, obs):
        self.phase = scheduler.update(obs)
        if self.plan is None or self.plan_age >= K or self.phase_changed:
            self.plan = self.vla.plan(obs, horizon=30)   # slow
            self.plan_age = 0
        base = self.plan.next(4)          # 4 步 delta chunk
        dpose, alpha = davs_step(obs, self.bank, self.phase)
        if dpose is not None:
            # 只修正当前要执行的第一步；后续步保持计划，避免把同一 delta 重复施加
            base[0] = blend_delta(base[0], dpose, alpha)
        status, p = verify(obs, self.phase, self.history)
        if status == "success":
            return hold_action(obs)
        if status == "failure":
            base = self.controller.retry_or_abort(obs, self.phase, base)
        self.plan_age += 1
        return base
```

### 7.4 需要 debug 验证的接口假设

1. `action_chunk_size` 是否固定？能否在 metadata 里设 4？
2. 评测调用 `get_action` 的频率是否等于控制频率？chunk 执行期间是否不调用？
3. `ee_pose` 是绝对还是相对？
4. `reset()` 是否清空策略状态？跨 episode 是否允许缓存参考库（只读，应该允许）？
5. 手册写“直至任务成功、失败或超时”，倾向成功即停；仍需确认 API 层是否继续调用、HOLD 是否被接受。
6. 延迟监控的阈值；超过是否扣分/中断？

这六个问题在 E0 用 debug 通道一次跑通；不要等到计分跑才发现。

不能在成功后继续执行计划；这是“把成功弄丢”的最常见方式。

## 9. 实验设计：先离线，再 debug，最后计分

### 9.1 原则

- **预注册**：E2/E4 前写死假设、主指标、停止规则；不看到结果再改。
- **debug 通道**：单任务不计分，用于迭代；计分跑只做最终验证，不用于调参。
- **按任务配对**：32 个任务同一组 trial；分析用 task-level paired bootstrap，不把 320 次当独立样本。
- **失败分类**：每次失败标“感知/抓取/对准/插入/扰动/超时/场景损坏”，否则无法定位。
- **不碰运气**：一次 debug 的 ±1 次波动不改主线；至少 5 次/任务。

### 9.2 实验矩阵

| ID | 目的 | 设置 | 主指标 | 通过标准 |
|---|---|---|---|---|
| E0 | 接口/基座 sanity | 1 任务，1 trial，发固定小动作 | 动作语义、延迟、reset | 6 个接口假设全部确认 |
| E1 | 离线 DAVS | 留出演示 + 人工扰动 | 伺服后位姿误差、检索命中率 | 误差降 ≥30%，命中 ≥70% |
| E2 | debug A/B/C/D | 8 任务（4 易 4 难）×5 trials | 成功率 | D 比 A +10pp，且假成功 <5% |
| E3 | 全任务扫 | 32 任务 ×1–2 trials | 成功率、失败分类 | 找到 top 5 失败模式 |
| E4 | 计分跑 | 32×10 | 成功率、步骤分 | 预注册分析；报告 CI |

A/B/C/D：

- A：WLA 基座（chunk=30/8，无 DAVS/retry）
- B：A + DAVS
- C：A + Critic + retry（无 DAVS）
- D：完整 RELAY

E2 的任务选择：T10、T26、T27、T19（精密/可重试）+ T01、T12、T14、T24（R1/R2/干扰）。每个 5 trials，共 40 episodes；先做 2 个任务做 smoke，再扩。

### 9.3 消融

| 消融 | 变量 | 目的 |
|---|---|---|
| chunk | 1 / 4 / 8 / 30 | 延迟 vs 伺服频率 |
| 基座 | WLA / MolmoAct2 | 基座是否瓶颈 |
| 相机 | 4 路 / 2 路（wrist+head L） | 带宽/延迟 vs 成功率 |
| 语言 | 1 条 / 5 条 | 复述鲁棒性 |
| DAVS | on/off | 最后一厘米收益 |
| retry | on/off | 预算收益 |
| critic | 阈值/校准 | 假成功 vs 重试率 |
| 参考库 | demo / 合成 / 无 | 参考帧质量 |

### 9.4 指标

- 主：任务成功率（均值 + 95% CI）。
- 次：步骤分、time-to-success、每次成功重试次数、干预次数、场景损坏率。
- Critic：AUROC、ECE、假成功率、失败召回。
- DAVS：检索命中率、inlier 数、收敛步数、退出率。
- 系统：p50/p95 延迟、超时率、chunk 饥饿率。

### 9.5 统计与决策

- 320 次 trial，按任务配对 bootstrap 10000 次；报告 95% CI。
- 目标 +10pp；E2 只有 40 episodes，不能做最终统计。若 D vs A <5pp 且 DAVS 触发率/收敛率低，先修实现（参考库、相机、标定）；只有在 DAVS 正常触发但收益仍 <5pp 时才缩主线。若 5–8pp，保留并扩到 E3；若 >10pp，直接进 E3/E4。
- 若 Critic AUROC <0.80 或假成功 >10%，先修 Critic，不加重试。
- 若 DAVS 检索命中 <50%，先修参考库/相机，不调伺服增益。

## 10. 离线验算与“预期结果”（不是真机结果）

### 10.1 本轮已经能确认的

- 排名是成功率字典序，步骤分只是 tie-break；PILOT 的“60% 步骤分”论证需要降级。
- 头部占位榜 <30%，成功率-步骤分差约 8.6pp；失败集中在最后一公里是可检验的假设。
- 官方 33k 演示、四路相机、5 条复述、WLA 微调代码、Dex1 支持都已就绪；数据/基座的工程就绪度不是当前瓶颈，基座能力是否够用由 H5 验证。
- 320 次 trial 的统计噪声约 2.6pp/模型；+10pp 是合理的最小目标，+5pp 不够稳。
- 重试在“可恢复 + 不损坏场景”的前提下，有 +13–25pp 的理论空间；R2 任务不能盲试。
- API 的 chunk/EE 语义/成功停止条件仍有 6 个未确认假设；必须先跑 E0。

### 10.2 模型推算（标注为推算）

**DAVS 收益**：设 30% 基线，失败中 `a` 比例是终局精密失败，DAVS 能修复其中 `f`：

| a（终局失败占比） | f（修复率） | 成功率提升 |
|---:|---:|---:|
| 40% | 20% | +5.6pp |
| 50% | 30% | +10.5pp |
| 60% | 40% | +16.8pp |

**组合**：基线 30% + DAVS +10.5pp = 40.5%；再做总尝试 2–4 次（1–3 次重试，ICC=0.4）：

| 配置 | 成功率（推算） |
|---|---:|
| 基线 | 30% |
| +DAVS | 40.5% |
| +DAVS + 总尝试 2 次（1 次重试） | 约 55% |
| +DAVS + 总尝试 3 次（2 次重试） | 约 63% |
| +DAVS + 总尝试 4 次（3 次重试） | 约 68% |
| 基线 + 总尝试 3 次（2 次独立重试，参考上界） | 约 66% |
| 基线 + 总尝试 4 次（3 次独立重试，参考上界） | 约 76% |

**结论**：45%+ 是可达的设计目标，但取决于 H1–H5；不要对外宣称“已经 45%”。E2 是第一个真实验证点。

### 10.3 失败情景

- 若 H1 不成立（失败不在终局）：DAVS 收益 <5pp，主线转向“抓取/搬运阶段”的伺服与重试。
- 若 H3 不成立（第二次几乎必败）：重试预算转向“第一次做对”，即更慢的接近、多视角验证。
- 若 H4 不成立（Critic 不可校准）：不能重试，退回“单次 + 成功保持”，并投入更多 debug 数据训练 Critic。
- 若 H5 不成立（WLA 微调 <20%）：先修基座/数据，RELAY 包络无意义。
