# 第 8 轮（本轮灵感循环第 2 轮）· BODY-GPR：模型不缺大脑，缺一个身体

> 检索/复核日期：2026-10-25（UTC）。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型，选手自部署 + 官方远程真机 API 评测。本轮三个灵感词是「本体感知」「开源硬件」「开放词汇」。我先承认上一轮的两个误读，再把三个词钉到本轮核实到的硬事实上，最后合成主判断：**头部 VLA 已经会“想”，但还不会“感觉自己的身体”；剩余成功率大量丢在接触、卡死、滑移、关节不可行和人为扰动这些身体级事件上。给任意强 VLA 外面包一层本体反射 + 开源运动学影子 + 离线开放词汇蒸馏，比再换一个更大的 VLA 更可能把近成功 episode 转成成功。** 一句话：上一轮攻“最后 3 厘米”，这一轮补“整条手臂的身体感”。

## 0. 先纠错：上一轮哪里错了

### 0.1 排名规则读错了：成功率是主排序，步骤分只是平分决胜

上一轮把步骤分当成与成功率并列的排序依据（隐含了很大权重），进而把“终局放置 ≈ 60% 步骤分”当成资源分配的第一性依据。官方参赛手册写得很清楚（[S12][S13]）：

> “实时榜单按 32 个任务的总平均成功率进行排序，成功率相同时按总平均步骤分排序，若仍相同，则提交日期较早的模型排序靠前。”

这句话的直接推论是：

1. **优化目标应是“把近成功 episode 转成成功”**，而不是“多拿一点部分分”。部分分只在成功率打平时才有用。
2. 终局放置仍然重要，但它的重要性来自**它是 32/32 任务的成功闸门**，不是来自“步骤分权重”。这两件事不能混为一谈。
3. 如果一个干预只提高步骤分、不提高成功率，它在排名上几乎不值钱；如果一个干预把“做到最后一步但掉了”变成“做成”，它同时改善成功率和步骤分。

上一轮的算术没有全错，但优先级错了：**先问“这一步是不是成功闸门”，再问“它值多少步骤分”**。

### 0.2 占位榜的 gap 不能当“失败深度”证据

上一轮用“步骤分 − 成功率 ≈ +8.6pp”推断“多数失败发生在后段步骤”。本轮把 8 个占位模型 × 32 任务全部展开后，任务级 `(平均成功率, 平均 gap)` 的相关系数是 **0.999**，每个任务的 gap 标准差只有 0.7–3.4pp，且 gap 几乎随任务平均成功率上升。这更像是占位脚本按任务难度注入了一个近似常数，而不是真实失败深度的独立信号。

结论：**占位榜只能当“任务难度先验”，不能当“失败发生在第几步”的证据。** 真实失败深度要靠离线步骤级诊断和调试槽，不靠占位 JSON。上一轮“所有失败都在终局”的强判断，降级为“终局是成功闸门，但早期接触/对齐失败同样可能致命”。

### 0.3 任务结构不支持“只看终局”

占位榜里成功率最低的一批任务恰好不是“最后摆放”型：

- Plug In Ethernet 17.7、Unlock 20.1、Spell robot 21.8、Organize Stationery 22.5、Open Pill Bottle 22.7、Hang the Cup 23.0、Pick Out Battery 23.3、Zip Up 23.4。
- 这些任务的核心难点是**插、拧、夹、挂、拉、拔**——第一下接触、对齐、力方向、夹持稳定性。它们不是“走到最后再摆正”的问题。
- 相反，Stack Cups 30.3、Conveyor Food Sorting 29.1、Paper Cup Stacking 28.1 这类“抓-放-叠”任务反而更高。说明“终局放置”不是唯一瓶颈，至少不是所有任务的瓶颈。

所以本轮的失败模型从“一个终局闸门”改成**一条身体级失败链**：接近 → 接触 → 夹持 → 插入/闭合 → 搬运 → 释放/静置 → 扰动恢复。每一段都可能有独立的失败模式。

### 0.4 上一轮漏了两个硬杠杆

1. **`action.pivot [7]`**：提交接口的共享动作键，数据集字段名是 `vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height`。上一轮只关注双臂和夹爪，完全没提这个键。它不是“第七个关节”，而是下半身/基座/高度通道。桌面任务未必需要大范围移动，但小范围调高、侧移、支撑可能改变可达性和放置姿态。**具体语义官方未文档化，本轮只做保守探索，不把它当主路径。**
2. **头戴立体对是标定好的**：HangCup 的 `meta/info.json` 里 `camera_params.head_stereo` 给出左右相机内参、畸变、`R`、`T`、`rectified: true`；基线约 **58.25mm**，`fx≈282`。这意味着 API 的 `cam_left_high` / `cam_right_high` 很可能可以用经典 SGBM 得到米制深度，不需要深度传感器，也不需要第二个学习模型。上一轮完全没利用这一点。

### 0.5 数据集和 API 的字段并不完全对齐

这是本轮新增的“部署 schema”问题。数据集有、但 API 观测里没有的字段包括：`state_torso`、`state_d435`、左右 `ee_pose_gripper_torso`、`waist_state_joint`、`recomputed_ee_valid`。API 动作里也没有 `action.lower_body` / `action.waist_action_joint`，只有 `action.pivot [7]`。

后果很直接：

- 训练时如果把 `state_torso` / `state_d435` / torso EE 位姿当输入，推理时会缺输入，模型分布直接错位。
- 训练时如果让模型输出 `action.lower_body` / `waist_action_joint`，推理时这些键不存在，动作对不上。
- 正确做法：**只把 API 存在的键喂给策略；torso/d435/waist/valid 只作为离线标签、标定和辅助监督；下半身只能通过 `action.pivot` 间接控制。** OHKS 可以用 `lower_body` 里的 waist 角和 URDF 把 base EE 推到 torso 系，补上缺失的 torso 位姿。

## 1. 三个灵感词，各自钉到硬事实上

### 1.1 本体感知：API 给的是位置，不是力；但位置残差就是力的影子

API 观测有双臂关节位置 `[7+7]`、夹爪 `[1+1]`、`lower_body [15]`（含 waist 三角）、左右 EE base 位姿 `[6+6]`；**没有关节速度、力矩、电流、触觉**。数据集的 `action.*` 和 `observation.state.*` 是成对的，所以可以构造：

```text
e_t = q_cmd,t − q_t                    # 跟踪残差（位置误差）
q̇_t = (q_t − q_{t−k}) / (kΔt)         # 有限差分速度
q̈_t = (q̇_t − q̇_{t−k}) / (kΔt)        # 有限差分加速度
```

这不是力矩，但在接触/卡死/超载时，位置跟踪残差会先变大；配合“命令还在继续、关节却不动”的时序特征，可以区分：

- 自由空间：残差小、速度跟得上、加速度平滑；
- 接触：残差在预期接触相位上升，但稳定；
- 卡死：残差持续大、速度接近零、命令仍在推进；
- 滑移/掉落：夹爪闭合但物体/EE 的相对运动不符合预期（需要腕部视觉做二次确认）；
- 扰动：残差突然尖峰，且不是命令造成的。

证据链：ThinkProprio 把本体感知当文本 token 早融合，视觉 token 减到 15%、延迟降 50% 以上（[S21]）；无传感器接触力估计用双阶段 LSTM 从位置/电流残差估力（[S23]）；ContactGuard 用动作条件潜世界模型做预接触监控（[S22]）。我们的差异是：**不学一个大世界模型，先用解析期望运动 + 演示基线做轻量残差检测，再把事件接到 VLA chunk 的终止/恢复上。**

### 1.2 开源硬件：G1/Dex1 的 URDF 是免费的身体图式

Unitree 公开了 G1 的 URDF/MJCF（[S14]），其中明确有 **`g1_29dof_mode_15_with_dex1_1`**：29 DoF 身体（6×2 腿 + 3 waist + 7×2 臂）+ 2×2 Dex1 手。这给了我们四件确定性能力：

1. **FK/IK 与坐标系**：base → torso → shoulder → elbow → wrist → Dex1；可以把 API 的 base EE 位姿转到 torso 系，补上 API 缺失的 torso EE；也可以把 EE 目标反解成关节。
2. **关节限位/速度/加速度可行性**：策略输出的动作先过一遍 URDF 限位与速率检查，避免“发出去才知道不可行”。
3. **自碰撞/桌面间隙/可达性**：用胶囊体近似做自碰撞，用桌平面做 clearance，用 Jacobian 可操作度做 reachability。放置目标不再只看“语义上对不对”，还看“身体上够不够得着”。
4. **Dex1 抓取几何**：二指夹爪的开口、指宽、接近方向；抓取点是否在指间、接近向量是否与物体表面冲突。这些都可以从 URDF 的 hand 链算出来。

这不是第二个学习模型，是确定性代码（Pinocchio/MuJoCo/自写 FK）。它可以在 1ms 级跑，适合放在策略和评测器之间做“动作可行性影子”。

### 1.3 开放词汇：教师只在离线打标，推理只留一个 checkpoint

UniBot 的“未见物品”轴要求模型识别同类但外观不同的物体。开放词汇检测/分割（Grounding DINO、SAM3、DINOv3、SAM3D）是最现成的工具，但**推理时加载它们会违反“单模型、不得混合多个模型”的规则**，也会增加延迟。

所以本轮的原则是：

```text
离线：开放词汇教师 → 物体/部件 mask、可供性点、支撑/槽位关系、步骤谓词
      ↓ 蒸馏/辅助头/特征对齐
在线：唯一 VLA checkpoint（+ 确定性代码）→ 动作
```

具体做三件事：

- **OVPL（Open-Vocabulary Privileged Labeling）**：用教师给 33k 演示打“物体/部件/可供性/关系/谓词”标签，蒸馏进 VLA 的辅助头；推理不加载教师。
- **SMSG（Stereo Metric Slot Grounding）**：用头戴立体对 + 经典 SGBM 得到米制深度，融合开放词汇 mask（来自蒸馏头或离线标签）估计容器/槽位/自由空间；SGBM 是算法不是学习模型，合规。
- **PPR（Proprioceptive Phase Retrieval）**：用本体运动签名做检索键，抗背景/外观；检索库是数据，不是第二个模型。

这条路线把“开放词汇”从“再挂一个检测器”改成“把开放词汇能力蒸进同一个模型”，既合规，又避免推理期多模型延迟。

## 2. 本轮主判断：补“身体层”，而不是换“大脑”

### 2.1 头部方案的共同结构：action chunk 开环执行

MolmoAct2 是 Molmo2-ER 主干 + flow-matching action expert，官方强调闭环操作，但输出仍是 action chunk；WALL-OSS-0.5 是 4B、20+ 本体、零样本真机；DreamZero 是 14B 视频世界模型、7Hz 闭环；GigaBrain-0 用世界模型生成数据 + RGBD + 具身 CoT（[S16]–[S20]）。它们的共同点是：**策略在 chunk 边界才看到新观测，chunk 内部是开环的**。

API 也确认了这一点：`action_chunk_size = T_a`，返回 `(T_a, …)` 的动作；评测器先执行 index 0，再按顺序执行其余，直到再次调用 `get_action`（[S6]）。这意味着：

```text
实际闭环频率 ≈ 控制频率 / T_a
```

如果控制是 30Hz、`T_a=4`，chunk 内部开环约 133ms，理想反馈上限约 7.5Hz；`T_a=8` 时约 3.75Hz，再叠加推理延迟会更低。**所谓“30Hz 反射”不能直接成立**，除非 `T_a=1` 且每步都能跑策略。上一轮的 SVL 也有同样的隐含错误：它假设每个放置点都能 30Hz 闭环，但接口是 chunk 执行。

这不是否定本体反射，而是要求把它设计成两种形态：

- **PRL-v0（chunk 边界反射，现实版）**：`T_a=4–6`，在每个 chunk 开始看一次本体残差；如果上一 chunk 出现卡死/滑移/扰动，就丢弃剩余动作，生成恢复 chunk（后退、对正、重抓、重试）。反馈 5–7.5Hz，足够抓“卡死”和“大扰动”，抓不到毫秒级碰撞。
- **PRL-v1（同 checkpoint 快速头，进取版）**：`T_a=1`，评测器每步调用；完整 VLA 每 N 步跑一次，中间由同一 checkpoint 里的轻量反射头输出 1 步残差动作。这样才有真正的每步反馈，但工程量和训练难度显著上升。

本轮把 PRL-v0 作为主交付，PRL-v1 作为 W5 之后的 Go/No-Go 分支；不把“30Hz”写成已经成立的事实。

### 2.2 成功率算术：把“近成功”转成“成功”

设基线成功率 p，失败 episode 中“已经到达终局步但没做成”的比例为 r。PRL 不能提高“到达终局”的概率，但可以把其中一部分终局失败转成成功：

```text
ΔSuccess ≈ (1−p) × r × conversion
```

如果 p≈0.30、r≈0.20、conversion≈0.30，则 Δ≈4.2pp；如果 conversion≈0.50，则 Δ≈7.0pp。这两个数都是示意，不是实测；但它们说明 PRL 的合理目标应是 +4–7pp 级，而不是 +1pp 级。它是**跨任务、跨轴、与 VLA 无关**的增益，可以和任何强 VLA 叠加，而且直接作用在成功率主排序上，不是步骤分 tie-break。

对早期接触型任务（插网线、开锁、拉拉链），PRL 的价值不是“终局转化”，而是“第一次接触就失败后，不要继续把整段 chunk 执行完”；对堆叠/放置型任务，价值是“滑移/掉落被及时发现并重试”。两类都算成功转化。

### 2.3 为什么不是“再训练一个更大的 VLA”

- 头部模型已经是 4B–14B 级，继续堆参数的数据/算力门槛高，且榜单头部不到 30%，说明瓶颈不全在语义容量。
- 真实评测的 5 个泛化轴里，位置/干扰物/背景/未见物品主要考感知与 grounding；人为干扰考恢复。**恢复是身体层问题，不是语言层问题。**
- PRL/OHKS/SMSG 都是模型无关的，可以直接包在 MolmoAct2、WALL-OSS、WLA 或我们自己的 checkpoint 外面；这比“再预训练一个底座”风险低、迭代快。
- 单模型合规：确定性代码 + 同一 checkpoint 内的头，不引入第二个推理模型。

### 2.4 失败链与组件映射

| 失败段 | 典型任务 | 主要信号 | 组件 |
|---|---|---|---|
| 目标/槽位 grounding 错 | 全部，尤其未见物品 | 语言 + 开放词汇 mask + 容器关系 | OVPL / PGL / SSG |
| 接近路径碰撞/不可达 | 插网线、放置、堆叠 | URDF 可达性、桌面间隙、立体深度 | OHKS / SMSG |
| 夹持失败/滑移 | 抓杯、抓工具、搬盒 | 夹爪闭合 + 残差 + 腕部视觉 | PRL / SVL / OHKS |
| 插入/闭合卡死 | 网线、插头、开锁、拉链 | 残差持续 + 速度近零 + 命令推进 | PRL / OHKS / SMSG |
| 力过大/变形 | 药瓶、拉链、插头 | 残差方向 + 柔顺策略 | PRL |
| 释放过早/掉落 | 叠杯、叠碗、挂杯 | 释放后位移 + 谓词 | PRL / SVL |
| 人为扰动/物体被移走 | human 轴 | 残差尖峰 + 视觉变化 | PRL / NRB / SSG |
| 长程误差累积 | 4–5 步任务 | 步骤谓词 + 相位 | SSG / ICR / PRL |

这张表是“为什么需要身体层”的最直接论证：八个失败段里，只有第一段主要是语义 grounding，其余七段都需要本体/运动学/接触信号。

### 3.1 组件与反馈率

| 组件 | 作用 | 运行频率 | 是否学习模型 | 合规边界 |
|---|---|---|---|---|
| GPR-VLA | 生成 action chunk | 每 T_a 步 | 是，唯一 checkpoint | 主模型 |
| PRL | 本体事件检测 + 恢复选择 | 每 chunk 边界（v0）；每步（v1） | 否/同 checkpoint 头 | 代码或同模型头 |
| OHKS | FK/IK、限位、碰撞、可达性 | 每 chunk / 目标点 | 否 | 确定性代码 |
| SMSG | 立体深度 + 槽位 | 关键帧 5–10Hz | 否（SGBM） | 经典算法 |
| OVPL | 离线标签 → 辅助头 | 训练期 | 教师离线 | 不上推理 |
| PPR | 运动签名检索 | 每步/每 chunk | 否（库是数据） | 数据 |

## 4. 风险与合规（先立后破）

- **反馈率风险**：API 是 chunk 执行，PRL-v0 只有 5–7.5Hz；不要把它宣传成 30Hz 力控。若 `T_a` 不能动态调整，PRL-v1 的每步反馈需要 `T_a=1` + 同 checkpoint 快速头，工程风险高。
- **单模型风险**：推理时只允许一个学习 checkpoint；SGBM 是经典算法，URDF 是代码，教师模型只在离线。模型卡要写清“哪个文件是唯一模型、哪些是确定性代码、哪些是离线标签”。
- **`action.pivot` 语义未知**：默认保持零/小范围；只在调试槽做小高度变化；不做大基座移动。
- **立体标定风险**：数据集 `head_stereo` 有内参/基线，但 API 的 `cam_left_high/right_high` 是否同一对、是否已校正、头到 base 的外参在线是否可得，都需要验证；失败则回退单目 + 已知尺寸。
- **URDF 失配风险**：真实机器人可能有装配误差/夹爪更换；OHKS 用软约束和 margin，不硬裁剪；先用演示回放校验 FK 与数据集 EE 位姿的误差。
- **PRL 误触发风险**：残差受摩擦、负载、温度影响；用滞回、去抖、冷却期、置信度阈值；高置信才中断 chunk，低置信只记录。
- **统计功效风险**：320 trials 下，单臂成功率的标准误约 2.56pp；两臂独立、双侧 5% 比较，+3pp 只有约 13% 功效，+5pp 约 27%；即使任务配对把相关拉到 0.5–0.7，+3pp 也只有约 21–32%，+5pp 约 48–69%。**320 trials 只对约 +10pp 量级的强干预有可接受功效（+8pp 约 57%，+10pp 约 76%）**。不要用正式跑追 +3pp；+3–5pp 的小效应先用离线回放/调试槽验证方向，正式跑只押 +10pp 量级的大效应。
- **规则风险**：外部数据/预训练权重/教师模型离线使用是否允许，手册摘录未写；默认 L2L OFF，教师只做标签，邮件确认后再扩大。
- **调试槽风险**：次数/成本未知；把每个大版本最多 1 槽当发布门，不做日常调参。

## 5. 一句话押注

**押注 PRL：在 VLA 的 action chunk 边界加一层由“动作−状态”跟踪残差、有限差分速度/加速度和 URDF 期望运动驱动的本体反射，先解决接触、卡死、滑移、扰动这四类身体级失败；用开源 G1/Dex1 运动学做动作可行性影子，用离线开放词汇教师蒸馏进同一 checkpoint，用头戴立体对提供米制槽位——不增加推理模型，直接把近成功转成成功。**

## 1. 事实核对（2026-10-25）

### 1.1 排名规则：成功率主排序，步骤分 tie-break

官方参赛手册中英文都明确（[S12][S13]）：

> 中文：“实时榜单按 32 个任务的 **总平均成功率** 进行排序，成功率相同时按 **总平均步骤分** 排序，若仍相同，则提交日期较早的模型排序靠前。”
>
> 英文：“The real-time leaderboard is sorted by overall average success rate across all 32 tasks. In the event of a tie, the overall average step score is used as the differentiator. If still tied, earlier submission dates rank higher.”

| 旧读法（第 7 轮） | 新读法（第 8 轮） | 后果 |
|---|---|---|
| 成功率与步骤分综合排序（隐含步骤分有很大权重） | 成功率主排序；步骤分只在成功率打平时使用 | 只提步骤分、不提成功率的干预几乎不值钱 |
| 终局放置 ≈ 60% 步骤分 ⇒ 第一目标 | 终局是 32/32 任务的成功闸门 ⇒ 第一目标仍是“做成”，不是“多拿部分分” | 目标从“部分分”改为“成功转化” |
| 预算按步骤分权重分配 | 预算按“成功闸门 × 可转化失败”分配 | PRL 这类“把近成功转成成功”的干预优先级上升 |

**必须记住的算术**：成功率是 32 个任务的平均，每个任务 10 次；一次成功/失败对总成功率的边际约 1/320 = 0.3125pp。320 trials 的噪声很大，不要用正式跑追小效应。

### 1.3 提交接口 v2：chunk 执行、pivot、单模型

`unibot_submission` README（[S6]，最后提交 2026-08-21，[S7]）核实：

- 观测：4 路 RGB（`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`，480×640）、双臂关节 `[7+7]`、夹爪 `[1+1]`、`lower_body [15]`、左右 EE base 位姿 `[6+6]`、`observation.language` 单字符串。
- **没有深度传感器、没有关节速度/力矩/电流/触觉**；`obs_delta_indices` 可声明“传哪些键 + 每键堆叠几帧”，用 `[-4,-2,0]` 这类偏移做有限差分。
- 动作：共享 `action.left_gripper/right_gripper/action.pivot [7]`；`control_space` 二选一 `joint`（`action.left_arm/right_arm [7]`）或 `ee`（`action.left_ee_pose_gripper_base/right [6]`），互斥。
- `action.pivot [7]` 是**必填共享键**，描述为 “Lower-body / pivot target”；数据集字段名 `vx, vy, angle_z, pivot_3, pivot_4, pivot_5, height`。**具体语义/安全范围官方未文档化。**
- `action_chunk_size = T_a`；评测器先执行 index 0，再按顺序执行其余，直到再次调用 `get_action`（[S6] §3）。**chunk 内部是开环的**；实际反馈频率受 `T_a` 和控制频率限制。
- 评测跨 N 台机器人随机顺序；每个端口独立 episode、独立 `reset`/history；共享后端要处理并发和状态隔离（[S6] §5）。N 的具体数值未公开。
- token 双处校验：`metadata.token` + 每次返回的 `meta.token`。
- 评测记录每步延迟和动作统计；异常/不稳定会进入可信度评估（[S6] §6）。

**工程含义**：`action.pivot` 必须返回；在未验证前保持恒定/零是风险较低的默认，但必须用 `run_client.py` 确认评测器接受，不要假定零一定安全。若要用它做小高度调整，先在调试槽验证，不要假定 `pivot_3/4/5` 的含义。`T_a` 是固定 metadata；若不能动态调整，PRL 只能在 chunk 边界工作。

### 1.4 数据集：字段、schema 缺口、立体标定

HangCup（[S4][S5]）：1,043 episodes、194,564 frames、30fps、`lastModified 2026-10-14`；四路相机 `head_stereo_left/right` + `wrist_left/right`；官方 collection 约 33k / 169h（[S3]）。

**数据集 vs API 的 schema 缺口**（本轮关键发现）：

| 数据集字段 | API 观测 | API 动作 | 用途 |
|---|---|---|---|
| `left_arm/right_arm [7]` | 有 | `joint` 模式有 | 策略输入/输出 |
| `left_gripper/right_gripper [1]` | 有 | 共享键有 | 策略输入/输出 |
| `lower_body [15]`（含 waist 3） | 有 | 无（只有 pivot） | 本体输入；waist 角可用于 OHKS |
| `left/right_ee_pose_gripper_base [6]` | 有 | `ee` 模式有 | 策略输入/输出 |
| `left/right_ee_pose_gripper_torso [6]` | **无** | **无** | 仅离线标签；OHKS 从 base+waist 推导 |
| `waist_state_joint [3]` | 无独立键（含在 lower_body） | 无 | OHKS/标定 |
| `state_torso [6]` | **无** | **无** | 仅离线标定 |
| `state_d435 [6]` | **无** | **无** | 仅离线头到 base 标定 |
| `recomputed_ee_valid [1]` | **无** | **无** | OHKS 在线重算 |
| `action.lower_body [15]` | — | **无** | 仅离线辅助监督 |
| `action.waist_action_joint [3]` | — | **无** | 仅离线辅助监督 |
| `action.pivot [7]` | — | **有（必填）** | 下半身/基座/高度通道 |

**结论**：训练/推理必须只使用 API 存在的键；torso/d435/waist/valid 只能做离线标签、标定和辅助监督。否则会出现“训练时有、推理时无”的模态缺口，这可能是真实泛化失败的一个隐蔽来源。

**头戴立体标定**（`meta/info.json` 的 `camera_params.head_stereo`）：

| 参数 | 左 | 右 |
|---|---:|---:|
| fx | 282.369 | 281.874 |
| fy | 282.752 | 282.319 |
| cx | 311.525 | 329.958 |
| cy | 256.628 | 249.512 |
| 畸变 | 5 参数 | 5 参数 |
| `R` | ≈ 单位阵 | — |
| `T` | `[-58.253, -0.168, 0.579]` mm | — |
| `rectified` | true | — |

基线约 **58.25mm**，`fx≈282`。按 `Z=fB/d`，桌面子 0.3–0.8m 的深度分辨率约为：

| 距离 Z | 视差 d | 每像素深度 |
|---:|---:|---:|
| 0.3m | 54.8px | 5.5mm |
| 0.5m | 32.9px | 15.2mm |
| 0.8m | 20.5px | 38.9mm |

SGBM 亚像素（1/4px）可把上表除以 4，即约 1.4–9.7mm。对放置/插入的粗定位足够，对毫米级精插仍要腕部视觉伺服。**注意**：`T` 是左右相机之间的基线，不是头到 base 的外参；头到 base 要用 `state_torso`/`state_d435`（若 `state_d435` 对应头部相机）离线标定，在线 API 没有这两个键。

**动作-状态成对**：数据集的 `action.*` 与 `observation.state.*` 可构造跟踪残差；没有力矩/电流，PRL 只能用位置残差作为“力的影子”。这是限制，也是本方案的诚实边界。

### 1.5 开源硬件：G1/Dex1 URDF 可用

Unitree 公开 G1 的 URDF/MJCF（[S14]），其中明确有 **`g1_29dof_mode_15_with_dex1_1`**：29 DoF 身体（6×2 腿 + 3 waist + 7×2 臂）+ 2×2 Dex1 手。可做：

- FK：关节 → base/torso → EE；IK：EE 目标 → 关节（带 waist/冗余）。
- 关节限位/速度/力矩（URDF 的 limit；力矩只用于可行性检查，不用于控制）。
- 自碰撞/桌面间隙/可达性/可操作度。
- Dex1 二指抓取几何：开口、指宽、接近方向、抓取点是否在指间。
- 把 API 的 base EE 位姿转到 torso 系，补上 API 缺失的 torso EE。

**限制**：URDF 是名义模型，真实机器人有装配误差/夹爪更换；OHKS 只能做软约束和 margin，不能硬裁剪。`action.pivot` 只暴露 7 维抽象，不能直接命令 `action.lower_body`/`waist_action_joint`；全身杠杆受限。

### 1.6 头部方案：action chunk 是共同结构

- **MolmoAct2**（Ai2，[S16]）：Molmo2-ER 主干 + flow-matching continuous action expert；官方强调闭环操作，但输出仍是 action chunk；公开材料明确其部署经验主要在 SO-100/Franka DROID，其他本体不保证。
- **WALL-OSS-0.5**（[S17][S18]）：4B、20+ 本体、gradient-bridged 预训练、零样本真机。
- **DreamZero**（[S19]）：World Action Model，14B 视频扩散，7Hz 闭环，跨本体少样本。
- **GigaBrain-0**（[S20]）：世界模型生成数据 + RGBD + 具身 CoT。
- PI-0.5（knowledge insulation）、GR00T N1.5 也在占位榜。

共同点：**策略在 chunk 边界才看到新观测，chunk 内部开环**。这不是某个模型的缺陷，而是当前 action-chunk 范式的结构。PRL 的定位不是替代它们，而是补它们共同缺的身体闭环。

### 1.7 失败模式：从任务语义出发

占位榜的低成功率任务（插网线、开锁、拉拉链、开药瓶、挂杯）主要是**接触/对齐/夹持**；高成功率任务（叠杯、分拣、纸杯堆叠）主要是**抓-放-叠**。这支持“失败链”而不是“单一终局闸门”：

| 失败段 | 典型任务 | 主要信号 | 组件 |
|---|---|---|---|
| 目标/槽位 grounding | 全部，尤其未见物品 | 语言 + 开放词汇 mask + 容器关系 | OVPL/PGL/SSG |
| 接近碰撞/不可达 | 插网线、放置、堆叠 | URDF 可达性、桌面间隙、立体深度 | OHKS/SMSG |
| 夹持失败/滑移 | 抓杯、抓工具、搬盒 | 夹爪闭合 + 残差 + 腕部视觉 | PRL/SVL/OHKS |
| 插入/闭合卡死 | 网线、插头、开锁、拉链 | 残差持续 + 速度近零 + 命令推进 | PRL/OHKS/SMSG |
| 力过大/变形 | 药瓶、拉链、插头 | 残差方向 + 柔顺策略 | PRL |
| 释放过早/掉落 | 叠杯、叠碗、挂杯 | 释放后位移 + 谓词 | PRL/SVL |
| 人为扰动/物体被移走 | human 轴 | 残差尖峰 + 视觉变化 | PRL/NRB/SSG |
| 长程误差累积 | 4–5 步任务 | 步骤谓词 + 相位 | SSG/ICR/PRL |

## 2. 问题定义：为什么补“身体层”

### 2.1 接口层：chunk 开环是硬约束

```text
评测器: obs_t → get_action → chunk a_{t:t+T_a-1} → 顺序执行 → obs_{t+T_a} → get_action ...
```

- `T_a=4`、控制 30Hz：chunk 内部 133ms 开环；理想反馈上限 7.5Hz，叠加推理延迟更低。
- `T_a=8`：内部 267ms 开环；反馈上限 3.75Hz。
- 只有 `T_a=1` 才能每步反馈，但 30Hz 跑 6B VLA 不现实；需要“慢 VLA + 同 checkpoint 快速头”的分层。

**所以 PRL 必须分两版**：

- **v0（主交付）**：chunk 边界反射；`T_a=4–6`；看上一 chunk 的残差历史，决定下一 chunk 是继续、缩短、恢复还是重规划。
- **v1（Go/No-Go）**：`T_a=1`；完整 VLA 每 N 步跑一次，中间由同一 checkpoint 的轻量反射头输出 1 步残差动作；需要额外的训练/延迟工程。

### 2.2 身体层：三个缺口

1. **接触/力缺口**：没有力矩/触觉；VLA 的 action chunk 在接触后仍按开环执行。需要从位置残差/速度/夹爪/EE 有效性推断接触、卡死、滑移、扰动。
2. **身体图式缺口**：VLA 不知道关节限位、自碰撞、桌面间隙、可达性、Dex1 抓取几何；动作可能“语义对、身体不可行”。需要 URDF 影子。
3. **米制/开放词汇缺口**：没有深度；未见物品需要开放词汇；但推理不能挂第二个模型。需要立体 + 离线蒸馏。

### 2.3 成功转化算术

```text
ΔSuccess ≈ (1−p) × r × conversion
p = 基线成功率
r = 失败中“近成功”（已到终局/已夹住/已对准但没做成）的比例
conversion = PRL 把近成功转成成功的比例
```

示意：p=0.30、r=0.20、conversion=0.30 ⇒ +4.2pp；conversion=0.50 ⇒ +7.0pp。这两个数不是实测，但说明 PRL 的合理目标是 +4–7pp 级，而不是 +1pp 级；也与“320 trials 只对 +10pp 量级有可接受功效”形成张力——所以必须用调试槽/离线回放先验证方向，正式跑只押大效应。

### 2.4 为什么不是“再训练一个更大的 VLA”

- 头部 4B–14B，继续堆参数的数据/算力门槛高；榜单头部不到 30%，瓶颈不全在语义容量。
- 5 个泛化轴里，位置/干扰物/背景/未见物品主要考感知/grounding；人为干扰考恢复。恢复是身体层问题。
- PRL/OHKS/SMSG 模型无关，可包在 MolmoAct2/WALL-OSS/WLA 或自己的 checkpoint 外；风险低、迭代快。
- 单模型合规：确定性代码 + 同一 checkpoint 内的头，不引入第二个推理模型。

### 3.2 数据流与延迟预算

| 模块 | 频率 | 目标延迟 | 备注 |
|---|---:|---:|---|
| GPR-VLA 前向 | 每 `T_a` 步 | <100–200ms | 取决于模型/硬件；chunk 摊销 |
| PRL | 每 chunk（v0）/每步（v1） | <5ms | 纯 CPU/小 MLP |
| OHKS FK/IK | 每 chunk/目标点 | <1ms/5ms | Pinocchio/MuJoCo |
| SMSG SGBM | 关键帧 5–10Hz | 20–50ms @320×240 | 与 VLA 异步 |

| SVL 视觉校验 | 释放前后 | 10–30ms | 腕部/头部 |

**原则**：快路径不阻塞慢路径；SGBM/检索在后台线程预取；`get_action` 的 p99 延迟要稳定（评测会记录延迟异常）。

### 3.3 单模型合规边界

| 组件 | 推理时形态 | 合规论证 |
|---|---|---|
| GPR-VLA | 一个 checkpoint 文件 | 唯一学习模型 |
| PRL 事件头 | 同 checkpoint 的轻量头 | 不是第二个模型；若用纯阈值则更安全 |
| OHKS | Pinocchio/MuJoCo/自写 FK | 确定性算法，不是学习模型 |
| SMSG | OpenCV SGBM | 经典算法，不是学习模型 |
| OVPL 教师 | 只在离线 | 不加载到推理 |
| PPR/ICR | 检索库 + 同模型编码 | 数据，不是模型 |
| PGL 锚点 | 几何投影/渲染 | 确定性代码 |
| SSG 谓词 | 同 checkpoint 头或规则 | 不是第二个模型 |

**如果规则把任何感知模块都当“模型”**：回退到“离线标签 + VLA 自己的深度/分割头”，不加载 SGBM 之外的任何网络；SGBM 也改为纯离线标定 + VLA 深度头。模型卡逐项披露。

## 4. PRL：本体反射层（主押注）

### 4.1 输入与信号

在每个 chunk 边界，PRL 拿到：

- 最近 `W` 步的本体历史：双臂 `q [14]`、夹爪 `[2]`、`lower_body [15]`（含 waist 3）、左右 EE base 位姿 `[12]`；
- 最近 `W` 步我们实际发出的命令：`q_cmd`、`gripper_cmd`、`pivot_cmd`；
- 当前 VLA 的 action chunk `a_{t:t+T_a-1}`；
- SSG 的当前步骤 `s_t`、语言、剩余时间、已用恢复次数；
- 可选：腕部/头部视觉的低频物体跟踪（用于滑移/掉落二次确认）。

核心信号：

```text
e_t     = q_cmd,t − q_t                       # 跟踪残差（位置误差）
z_t     = (e_t − μ_s) / σ_s                   # 按步骤/速度/夹爪条件归一化
q̇_t     = (q_t − q_{t−k}) / (kΔt)            # 有限差分速度
q̈_t     = (q̇_t − q̇_{t−k}) / (kΔt)           # 有限差分加速度
speed   = ||q̇_t|| / (||q̇_cmd,t|| + ε)
persist = 连续满足“高残差 + 低速度 + 命令推进”的步数
spike   = ||e_t − e_{t−1}|| / σ_s             # 扰动尖峰
```

`μ_s, σ_s` 来自演示：按任务/步骤/速度桶/夹爪状态统计自由空间残差的中位数与 MAD；`σ_s` 用 MAD 的稳健估计，避免被接触段污染。`q̇`、`q̈` 用 Savitzky–Golay 或一阶低通，30Hz 下不要直接差分。

### 4.2 事件分类

| 事件 | 触发条件（示意） | 置信度 | 典型动作 |
|---|---|---|---|
| `FREE` | `|z| < 3`，速度跟得上，命令连续 | 高 | 继续 |
| `CONTACT` | `|z|` 在预期接触相位上升，但稳定；`speed` 0.3–0.8 | 中 | 减速/柔顺 |
| `JAM` | `|z| > 6` + `speed < 0.2` + `persist ≥ 3` | 高 | 后退 5mm → 对正 → 慢速重试 |
| `SLIP` | 夹爪闭合 + 腕部视觉物体相对 EE 位移 > 阈值 + 残差下降/尖峰 | 中高 | 停 → 重抓 |
| `DROP` | 夹爪闭合但物体不再随 EE 运动（视觉） | 高 | 停 → 重抓/重放 |
| `DISTURBED` | `spike > 8` 且非命令造成；视觉物体/EE 突变 | 高 | 停 → 重新定位 → 重规划 |
| `LIMIT` | 关节接近 URDF 限位/速度限 | 高 | OHKS 投影/换手/调高 |
| `INVALID` | OHKS FK 与 API EE 位姿不一致，或 IK 不可行 | 高 | 用 FK/重规划 |
| `COLLISION` | 残差 + 视觉接近/桌面间隙不足 | 中高 | 后退 → 绕行 |

**诚实边界**：没有力矩/触觉，`JAM` 是“高残差 + 低速度 + 命令推进”的代理，不是力阈值；`SLIP`/`DROP` 必须靠视觉二次确认，不能只靠本体。PRL 的输出是“事件 + 置信度”，不是“力”。

### 4.3 决策策略

```text
高置信 JAM/DROP/DISTURBED/INVALID/LIMIT → 中断剩余 chunk，进入恢复
中置信 CONTACT/SLIP/COLLISION        → 减速/柔顺/缩短 chunk，下一 chunk 再判
低置信                               → 只记录，不改变动作
```

恢复原语：

| 原语 | 语义 | 适用 |
|---|---|---|
| `HOLD` | 保持当前位置/夹爪，等待一个短窗口 | 接触稳定/不确定 |
| `BACKOFF(d)` | 沿接近方向后退 d（5–10mm） | JAM/COLLISION |
| `REAPPROACH` | 重新对正后慢速接近 | JAM/插入 |
| `REGRASP` | 张开→重新定位→闭合 | SLIP/DROP |
| `RETRY` | 重放当前步骤的上一段 | 释放失败/放置偏差 |
| `REPLAN` | 丢弃当前 chunk，带恢复 token 重新调用 VLA | 扰动/步骤失败 |
| `STEP_BACK` | SSG 回退一步（谓词从 1→0） | 被撤销/物体移走 |
| `ABORT` | 放弃当前 episode 的剩余动作（保守） | 时间/安全 |

**预算**：每个步骤最多 2 次恢复；每个 episode 最多 4 次；长程任务（4–5 步）最多 2 次；剩余时间 <20s 时只允许 `RETRY`/`ABORT`，不再做长恢复。恢复失败要回到 VLA，而不是无限重试。

### 4.4 标定与阈值

1. **自由空间基线**：用每个 episode 的前 1–2s（通常是接近段）估计 `μ_s, σ_s`；如果一开始就接触，用演示的全局基线。
2. **按步骤条件化**：抓取/插入/释放段的残差分布不同；用 SSG 步骤标签分桶。
3. **滞回**：进入 `JAM` 用高阈值（6σ），退出用低阈值（3σ）；避免抖动。
4. **去抖/冷却**：事件连续 3 步才确认；同一事件 1s 内不重复触发；恢复后 0.5s 冷却。
5. **速度归一化**：快速段残差天然大；用 `speed` 和命令加速度归一化，避免“越快越容易误判”。
6. **离线校验**：在演示回放中注入卡死/滑移/扰动，测事件查准/查全；要求 `JAM` 查准 >80%、误触发 <5%/episode 才上真机。

### 4.5 学习头（可选，同 checkpoint）

- 输入：`W=8–16` 步的 `q, q_cmd, e, q̇, q̈, gripper, EE` + 步骤/语言嵌入。
- 输出：9 类事件 logits + 8 类恢复原语 logits。
- 结构：1D conv/GRU + MLP，<1M 参数；放在 VLA checkpoint 的辅助头里，不单独加载。
- 标签：
  - 演示自由空间/接触：用相位 + 夹爪事件自动标；
  - JAM/SLIP/DROP：在仿真/回放中注入（推挤、拔起、延迟闭合、桌面抬高）；
  - DISTURBED：官方 human 备注剧本 + 随机平移；
  - 类别不平衡：focal loss + 类别权重。
- 训练：与 VLA 联合微调或冻结 VLA 只训头；若标签不足，纯阈值版优先。
- 合规：头在同一 checkpoint 内；推理仍是一个模型。

### 4.6 伪代码

```python
# 伪代码：省略网络发送/状态更新细节
class PRL:
    def __init__(self, urdf, demo_stats, cfg):
        self.ohks = OHKS(urdf)
        self.stats = demo_stats          # per-step mu/sigma
        self.cfg = cfg
        self.hist = deque(maxlen=16)
        self.last_cmd = None
        self.last_chunk = None

    def observe(self, obs):
        self.hist.append(parse_proprio(obs))   # q, gripper, ee, lower_body
        self.hist[-1].ee_valid = self.ohks.check_ee(self.hist[-1])

    def detect(self, cmd_hist, phase):
        q, qd, qdd = filter_and_diff(self.hist)
        e = cmd_hist - q
        z = normalize(e, self.stats[phase])
        speed = norm(qd) / (norm(cmd_hist.qd) + 1e-6)
        persist = count(lambda t: abs(z[t]) > 6 and speed[t] < .2)
        events = []
        if persist >= 3 and cmd_hist.still_pushing:
            events.append(Event("JAM", conf=min(1, persist / 5)))
        if spike(z) > 8 and not commanded_spike(cmd_hist):
            events.append(Event("DISTURBED", conf=.9))
        if not self.hist[-1].ee_valid:
            events.append(Event("INVALID", conf=1.0))
        if vision_says_slip(self.hist, self.last_chunk):
            events.append(Event("SLIP", conf=.7))
        if vision_says_drop(self.hist, self.last_chunk):
            events.append(Event("DROP", conf=.9))
        ...
        return events

    def gate(self, chunk, obs, phase, budget):
        self.last_chunk = chunk
        events = self.detect(self.last_cmd, phase)
        high = [e for e in events if e.conf >= .8]
        if "JAM" in high:
            return self.recovery("BACKOFF_REAPPROACH", obs, budget)
        if "DROP" in high:
            return self.recovery("REGRASP", obs, budget)
        if "DISTURBED" in high:
            return self.recovery("REPLAN", obs, budget)
        if any(e.name == "CONTACT" and e.conf >= .5 for e in events):
            return self.moderate(chunk, speed=.5, compliance=True)
        return chunk
```

### 4.7 与相关工作的差异

| 工作 | 做法 | 我们的差异 |
|---|---|---|
| ContactGuard（[S22]） | 动作条件潜世界模型 + 视觉，预接触监控，异常中止 | PRL 用本体残差，不学大世界模型；不仅中止，还给恢复原语；可包在任意 VLA 外 |
| 无传感器接触力估计（[S23]） | 从位置/电流残差估计力 | 我们不做力回归，做事件分类 + 恢复选择；没有电流，只用位置残差 |
| ThinkProprio（[S21]） | 本体当 token 早融合进 VLA | 我们是外挂反射层，不改 VLA 主干；可与 ThinkProprio 叠加 |
| WHOLEBODYVLA / HOIST（[S26][S27]） | 用全身动作/蹲下/侧移完成放置 | 我们用本体反馈做反射；全身动作只通过 `action.pivot` 保守探索 |
| 工业安全监控 | 超限即停 | 我们做任务级恢复（后退/重抓/重试），不是只停 |

### 4.8 失败模式与限制

- **无扭矩**：残差是摩擦、负载、温度、控制增益的混合；阈值必须按任务/步骤标定，不能跨任务硬套。
- **滑移/掉落不能只靠本体**：必须有腕部视觉或物体跟踪；否则 PRL 只能判“异常”，不能判“掉了”。
- **chunk 边界延迟**：v0 只能事后反应；对毫秒级碰撞无能为力。v1 需要 `T_a=1` 和快速头，工程风险高。
- **误触发**：频繁中断会破坏 VLA 的连贯动作，反而降低成功率；高置信才中断，中置信只减速。
- **学习头标签不足**：演示都是成功轨迹，JAM/SLIP/DROP 样本少；先用注入扰动 + 阈值版，学习头作为 W5 之后的增强。
- **单模型边界**：头必须在同一 checkpoint；如果规则不允许辅助头，回退纯阈值版。

## 5. OHKS：开源运动学影子

### 5.1 URDF 与坐标

使用 `g1_29dof_mode_15_with_dex1_1`（[S14]）：

- 29 DoF 身体：6×2 腿、3 waist、7×2 臂；另有 2×2 Dex1 手。
- 坐标系：base → pelvis/torso → waist → shoulder → elbow → wrist → Dex1；API 的 EE 位姿在 base 系，数据集另有 torso 系。
- API 没有 torso/d435 状态；OHKS 用 `lower_body` 里的 waist 角 + URDF 把 base EE 推到 torso 系；头到 base 用离线标定（§6.4）。

### 5.2 FK/IK/限位/碰撞/可达性

| 能力 | 方法 | 用途 |
|---|---|---|
| FK | URDF 链式变换 | 校验 API EE 位姿；补 torso EE；Dex1 指间点 |
| IK | 阻尼最小二乘 + waist/冗余 | EE 目标 → 关节；不可行时投影 |
| 限位 | URDF limit + margin | 关节角/速度/力矩可行性 |
| 自碰撞 | 胶囊体近似 + broadphase | 双臂/手/躯干干涉 |
| 桌面间隙 | 桌平面 + 立体深度/已知高度 | 接近/放置不撞桌 |
| 可达性 | 工作空间包络 + Jacobian 可操作度 | 选可达放置目标 |
| Dex1 几何 | 指宽/开口/接近向量 | 抓取点/姿态可行性 |

阻尼最小二乘 IK：

```text
Δq = Jᵀ (J Jᵀ + λ²I)⁻¹ Δx
q_{k+1} = q_k + α Δq,  s.t. q_min ≤ q ≤ q_max
```

可操作度：`w = sqrt(det(J Jᵀ))`；低于阈值的目标标记为“勉强可达”，优先换手/调高/换放置点。

### 5.3 动作投影

```python
def project(action, state):
    # 1) EE 模式：IK 到关节；失败则把目标拉回可达包络
    if action.space == "ee":
        q_target, ok = ohks.ik(action.ee, state.q, waist=state.waist)
        if not ok:
            action.ee = ohks.clip_to_reachable(action.ee, margin=0.02)
            q_target, ok = ohks.ik(action.ee, state.q, waist=state.waist)
    # 2) 关节模式：限位/速率/自碰撞软约束
    q_target = clip_to_limits(action.q, margin=0.05)
    q_target = limit_rate(q_target, state.q, qdot_max)
    if ohks.self_collision(q_target):
        q_target = ohks.project_out_of_collision(q_target)
    # 3) pivot：默认保持；只有显式请求才小范围改 height
    action.pivot = hold_or_small_height(action.pivot, state, max_dh=0.01)
    return action
```

**原则**：软约束优先，不硬裁剪策略输出；只有当动作确定不可行（超限/自碰撞/IK 不收敛）时才投影。投影后的动作要记录“修改量”，作为诊断/训练标签。

### 5.4 可达放置与 `action.pivot`

- PGL/OPT 给出容器系目标后，OHKS 检查：
  - 目标 EE 位姿是否在双臂可达包络内；
  - 接近路径是否撞桌/撞容器/自碰撞；
  - Dex1 指间是否能容纳物体；
  - 释放姿态是否在关节限位内。
- 不可达时，按优先级调整：换手 → 调整放置点（沿容器自由空间）→ 小范围 `pivot.height`（≤1cm）→ 放弃该目标。
- **`action.pivot` 语义未核实**：`vx, vy, angle_z` 可能是基座速度/朝向，`height` 可能是高度；`pivot_3/4/5` 未知。默认零/保持；只在调试槽做 ±1cm 高度测试；不做大基座移动。
- 全身 VLA 的证据（WHOLEBODYVLA 的蹲下/侧移、HOIST 的全身放置、Affordance-Guided Base Placement 的基座选择，[S26]–[S28]）说明全身动作有价值，但 UniBot API 只给了 `pivot` 抽象，不能直接命令腿/waist 关节；所以本轮只做保守探索。

### 5.5 训练期用途

- 给 ACP/GF 合成动作打“可行性”标签：不可行动作不进训练，或降权。
- 给 OPT 的放置目标打“可达性”标签：只保留可达目标。
- 给 PRL 提供期望运动/FK 校验：`INVALID`/`LIMIT` 事件。
- 给 SSG 的谓词提供几何特征：EE 到容器距离、夹爪开口、桌面高度。
- 可选辅助损失：预测关节限位 margin / EE 有效性；权重小，防止干扰主损失。

### 5.6 风险

- URDF 与真实机器人失配：用演示回放校验 FK 与数据集 EE 位姿，误差 >2cm 时降级为软约束。
- Dex1 几何/夹爪更换：以实际 URDF 为准；抓取点留 5mm margin。
- 桌高/相机外参未知：SMSG 估计桌平面；失败则用演示统计。
- IK 多解/冗余：用 waist/肘部偏好 + 上一帧解做正则，避免跳变。
- 计算延迟：FK 1ms、IK 5ms；不要在每个 30Hz 步都跑全量 IK，只在 chunk 边界/目标点跑。

## 6. SMSG：头戴立体米制槽位

### 6.1 标定与前置

数据集 `meta/info.json` 的 `camera_params.head_stereo` 已给出左右内参、畸变、`R`、`T`、`rectified: true`（[S5]）。基线约 58.25mm，`fx≈282`。使用步骤：

1. 确认 API 的 `cam_left_high` / `cam_right_high` 与数据集 `head_stereo_left/right` 是同一对相机（用图像内容/标定板/EE 投影验证）。
2. 若 API 图像已校正：直接用；若未校正：用 `cv2.stereoRectify` + `initUndistortRectifyMap`，左右用同一组 `image_resize`，并同步缩放内参。
3. 头到 base 的外参：数据集有 `state_torso`/`state_d435`（需确认 `state_d435` 是否对应头部相机），可离线估计 `T_base_head`；API 没有这两个键，在线用 `lower_body` 的 waist 角 + 固定 neck 假设，或每台机器人一次性标定。**这是 SMSG 最大的未核实点。**

### 6.2 SGBM 配置与深度精度

```python
stereo = cv2.StereoSGBM_create(
    minDisparity=0,
    numDisparities=96,       # 16 的倍数；覆盖 0.2–1.5m
    blockSize=5,
    P1=8*3*5**2, P2=32*3*5**2,
    disp12MaxDiff=1,
    uniquenessRatio=10,
    speckleWindowSize=100,
    speckleRange=2,
    mode=cv2.STEREO_SGBM_MODE_HH,
)
```

- 分辨率：320×240 用于 10Hz 预览；640×480 用于释放前关键帧。
- 视差范围：`d=fB/Z`；Z=0.2m → 82px，Z=1.5m → 11px；96 足够。
- 后处理：中值滤波 + 左右一致性 + 唯一性/斑点置信度；低置信像素置无效，不要用“看起来平滑”的深度。
- 精度：§1.4 表；0.3m 处 5.5mm/px，0.8m 处 38.9mm/px；亚像素可到 1.4–9.7mm。适合粗定位/槽位，不适合毫米级精插；精插靠腕部视觉伺服 + PRL 卡死检测。

### 6.3 容器/槽位/自由空间

- 用 OVPL 蒸馏头（或离线标签）给头部图像物体/容器 mask；用深度把 mask 投到 3D。
- 平面/箱体拟合：RANSAC 桌面平面、容器开口平面；估计容器 6D 位姿（PnP/ICP）。
- 槽位：在容器局部坐标系里找自由空间/分隔格；结合语言（“leftmost/middle/on the rack”）选候选。
- 自由空间：深度 + mask 得到可放置区域；用 OHKS 检查可达性/碰撞；输出给 PGL/OPT。
- 关键帧：抓取前、放置前、释放后；不需要每帧。

### 6.4 头到 base 外参

| 路径 | 数据 | 可行性 |
|---|---|---|
| 离线标定 | `state_torso` + `state_d435`（若对应头相机）+ 相机参数 + EE 投影 | 高；但 API 无 torso/d435 |
| 在线近似 | `lower_body` waist 角 + 固定 neck/head 偏移 | 中；需验证 neck 是否固定 |
| 每机器人一次性标定 | 标定板/已知桌面点 | 高；但评测多机，需每台做 |
| 桌面平面 + 已知桌高 | 立体深度拟合平面 | 中；桌高可能变化 |
| 纯相机系相对目标 | 容器系/EE 系相对位姿 + 视觉伺服 | 中；不依赖 base 外参，但需要手眼 |

**建议**：优先“离线标定 + 在线 waist 补偿”；失败则用“相机系相对目标 + EE 视觉伺服”，不要让整个系统依赖一个未验证的外参。

### 6.5 合规与回退

- SGBM 是 OpenCV 经典算法，不是学习模型；合规风险低。
- 如果使用学习型立体匹配/深度补全，只能离线蒸馏，或把深度头放进同一 checkpoint；不要推理时加载第二个网络。
- 回退：单目 + 已知物体尺寸/桌高；或纯 VLA + PGL 锚点；或腕部视觉伺服。
- 透明/反光/无纹理物体：SGBM 会失败；用腕部相机、边缘/颜色、或直接跳过深度，改用相对位姿。

### 6.6 风险

- API 相机与数据集不是同一对/分辨率不同 → 重新标定或放弃。
- 头随 waist/neck 运动 → 外参漂移；用 waist 角补偿/每帧重估。
- 运动模糊/光照 → 关键帧选静止/慢速时刻。
- 计算延迟 → 异步、低分辨率、关键帧。
- 深度精度不足 → 只做粗槽位，精插靠腕部伺服 + PRL。

## 7. OVPL：开放词汇特权标签 → 单模型蒸馏

### 7.1 教师与标签

离线教师（只在训练期）：

| 教师 | 输出 | 用途 |
|---|---|---|
| Grounding DINO | 开放词汇框 | 物体/容器/部件定位 |
| SAM2/SAM3 | 分割 mask | 物体/部件/可抓区域 |
| DINOv3 | 稠密特征 | 特征对齐/检索 |
| SAM3D | 3D/6D 候选 | 容器/物体位姿 |
| DepthAnything（可选） | 单目深度 | 无立体时的辅助 |

标签 schema：

```json
{
  "frame_id": "...",
  "objects": [{"name": "cup", "mask": "...", "box": [...], "affordance": ["handle"]}],
  "relations": [{"subject": "cup", "predicate": "on", "object": "rack"}],
  "slots": [{"container": "rack", "free_space": "...", "anchor": [x,y,z]}],
  "step": {"id": 1, "predicate": "hanging", "phase": "place"},
  "grasp": {"point": [x,y,z], "approach": [vx,vy,vz], "width": 0.04}
}
```

### 7.2 蒸馏进唯一 checkpoint

- **辅助头**：轻量 mask decoder（2–4 层 conv/transformer）、affordance heatmap、relation classifier、step predicate head。
- **特征对齐**：VLA 视觉特征与 DINOv3/SAM 特征做 cosine/contrastive 对齐；只训练投影层，不改主干或小 LoRA。
- **训练数据**：33k episodes 中抽样 10–20% 帧（约 2–6 万帧），主动学习选不确定性高的帧；人工抽检 5–10%。
- **损失**：`L = L_flow + λ_mask L_mask + λ_aff L_aff + λ_rel L_rel + λ_pred L_pred + λ_align L_align`；辅助权重从小开始，避免干扰动作主损失。
- **推理**：只跑 VLA + 辅助头；不加载教师。辅助头输出给 PGL/SSG/PRL/SVL。
- **合规**：教师是离线标签工具；辅助头在同一 checkpoint；模型卡披露。

### 7.3 数据/QA/许可

- 标签噪声：教师置信度阈值 + 多教师一致性 + 人工抽检；低置信不进训练。
- 域差：教师在大规模网络图像上训练，桌面/机械臂域可能偏；用官方演示微调/提示工程 + 人工校验。
- 许可：Grounding DINO、SAM2/3、DINOv3、SAM3D 的许可证逐个核对；比赛期间只用于内部标签，不 redistribution。
- 规则：若外部预训练模型连离线都禁止，回退到人工/经典 CV 标签；OVPL 降级为可选。

### 7.4 为什么能帮“未见物品”轴

未见物品轴是“同类但外观不同”。闭集检测器/固定类别头会失败；开放词汇教师能给出“杯子/把手/架子”等语义 mask，蒸馏后 VLA 学到的是“功能/部件”而不是“这个颜色的杯子”。这比在推理时挂一个开放词汇检测器更合规，也更轻。

### 7.5 风险

- 教师标签错误 → 辅助头学偏；用一致性/人工抽检/小权重。
- 蒸馏不充分 → 推理时没有教师就退化；用“教师在线蒸馏 + 学生单独推理”对比，确保学生独立可用。
- 许可/规则 → 默认只做内部标签；邮件确认。
- 算力 → 教师打标是离线一次性成本；抽样 + 主动学习控制。

## 8. PPR：本体相位检索

### 8.1 动机

视觉/语言检索键在背景/光照/未见物体变化下会漂移；运动签名（关节速度、EE 速度、加速度、跟踪残差、夹爪事件）描述的是“正在做什么”，对外观不敏感。FlowRetrieval 已经证明运动相似度检索比视觉/语言更跨场景（[S38]）；我们把“本体运动签名”作为检索键，和 ICR 的关系/视觉键融合。

### 8.2 键与检索

```text
segment = 演示按 SSG 步骤/相位切段（1–2s）
key = [mean/std(q̇), mean/std(q̈), mean/std(EE vel), mean/std(e),
       gripper_event_hist, phase_onehot, language_embed]
norm = 按任务/速度分桶标准化 + PCA/whitening
index = HNSW（余弦/欧氏）
K = 1–4
```

- 相位对齐：用 DTW 或步骤标签对齐；避免“抓取段”检索到“放置段”。
- 值：同 checkpoint 的上下文编码（离线预计算）+ 动作先验（K 段动作的稳健均值）。
- 融合：`score = α·PPR + β·ICR_visual + γ·language`；接触丰富/遮挡时 α 高，语义选择时 β 高。
- 延迟：HNSW <5ms；编码离线；K 小。

### 8.3 与 ICR 的关系

| 维度 | ICR（第 7 轮） | PPR（本轮） |
|---|---|---|
| 键 | 关系关键点 + 语言 + 相位 | 本体运动签名 + 相位 |
| 强项 | 语义/空间 grounding | 外观不变、接触/运动相似 |
| 弱项 | 背景/外观漂移 | 任务/速度变化 |
| 融合 | 视觉/关系为主 | 运动为主，接触段加权 |

### 8.4 风险

- 速度/风格差异 → 按任务/速度分桶 + 时间归一化。
- 任务多解 → 语言/步骤标签约束。
- 检索库偏差 → 只取官方演示；合成数据单独标记。
- 延迟 → 缓存/降 K/异步预取。

## 9. 与第 7 轮组件的整合

### 9.1 SSG：从“步骤分优化器”改为“成功闸门与诊断器”

- 输入：官方 `score_steps`（32 任务，满分 100）+ 5 条复述/中文描述。
- 构建：线性步骤图 `s0→…→sk`，附权重；指令匹配 160 条 + 规范化 + 嵌入兜底。
- 运行：谓词头 + 事件校验确认完成后才前进；未确认则重试/回退；human 撤销触发 `s_t←s_{t-1}`。
- 价值：
  1. 成功闸门：防跳步/假完成；
  2. 诊断：每任务每步完成率，找出“钱丢在哪一步”；
  3. 给 PRL/PPR/OPT 提供相位标签。
- **不再**用步骤权重做资源分配的主依据；权重只用于诊断和 tie-break 分析。
- 谓词来源：TLE 标签 + 少量人工抽检；谓词头可与 OVPL 共享视觉特征。

### 9.2 PGL/OPT/SVL：保留，但换成“身体可行 + 米制 + 滑移校验”

- **PGL**：槽位/区域 → 2D 锚点 → 6D 位姿；锚点来自 SMSG/OVPL，位姿来自 OPT；OHKS 检查可达/碰撞。
- **OPT**：K 条演示的容器系释放位姿统计；用 OHKS 过滤不可达，用 SMSG 估计容器位姿；离散度决定直接执行/慢速伺服/退化。
- **SVL**：缓放 → 静置/滑移校验 → nudge/regrasp/retry；滑移/掉落信号来自 PRL + 腕部视觉；预算 ≤2 次，长程 ≤1 次。
- 目标从“多拿终局步骤分”改为“把终局做成”；步骤分是副产品。

### 9.3 ICR/NRB：加 PPR，保留 human 剧本

- ICR：关系/语言/视觉键 + 缓存上下文；加 PPR 运动键融合。
- NRB：官方 human 备注（T10 拔插头、T12 拿走锁、T14 拧回瓶盖、T17 合上再打开、T19 拉开拉链、T24 物品回起点、T25 挪底座、T27 叠了第二个又拿走等）构造破坏→恢复对；训练恢复 token/可逆信念。
- 恢复训练与 PRL 的恢复原语共享标签；PRL 在推理时触发，NRB 在训练时教 VLA“怎么恢复”。

### 9.4 L2L/DebugLoop：外部数据默认 OFF，调试槽是发布门

- L2L：背景/位置多样性数据；规则未明，默认 OFF；邮件确认后再开。
- DebugLoop：不计分单任务调试槽；每个大版本 1 槽；任务选择：
  - T10 PlugCharger / T26 PlugInEthernet：插入 + JAM；
  - T12 Unlock：接触/拧转；
  - T19 ZipUp / T31 OrganizePencilCase：拉链/闭合；
  - T27 StackBowls / T01 HangCup：释放/滑移；
  - T14 PourOutMedicine：开盖/倾倒。
- 判定：PRL 近成功转化率 ≥20%、误触发 <5%/episode、无安全/超时回归，才进正式跑。

### 9.5 GPR-VLA/TLE/ACP/GF：单 checkpoint + 数据引擎

- GPR-VLA：WLA-1.0-Base（6B，Apache-2.0，24GB 可微调；[S29]）+ LoRA/action expert；承接语言、4 视图、本体、步骤、检索上下文。
- TLE：步骤相位 + 谓词/接触标签 + 放置位姿库；本轮只服务身体层/放置。
- ACP：位置/背景/干扰物配对；未见物品只对刚体任务；合成动作先过 OHKS 可行性。
- GF：软权重；合成不主导（<30%）。
- 新增辅助头：PRL 事件、OVPL mask/affordance、SSG 谓词；都在同一 checkpoint。

### 9.6 FLEET/TCLB：保留为工程检查单/离线比较台

- FLEET：N 端口并发、独立 reset/history、健康检查、延迟 p99、RTC 式弹性；不做“第六轴”研究。
- TCLB：离线相对比较台，不做模型选择；真机反馈靠调试槽。

## 11. 评测协议

### 11.1 离线（每天）

- 演示回放：只用 API 存在的字段训练/推理，验证 schema 对齐；对比数据集 EE 位姿与 OHKS FK，目标 <2cm。
- 注入扰动：卡死（桌面抬高/物体固定）、滑移（夹爪延迟闭合/物体变重）、扰动（目标平移/拿走）、遮挡（背景替换）。
- 指标：PRL 事件查准/查全/误触发；OHKS 不可行动作率；SMSG 深度误差/槽位误差；OVPL mask IoU/可供性命中；PPR 检索相位准确率。

### 11.2 本地（每周）

- TCLB 降级为“离线相对比较台”：32 任务的关键子集，回放/孪生混合，只做失败挖掘，不做模型选择。
- 关键子集：T10、T12、T14、T19、T26、T27、T01、T31。

### 11.3 调试槽（版本门）

- 每个大版本 1 槽；任务选择：
  - 插入/JAM：T10 PlugCharger、T26 PlugInEthernet；
  - 接触/拧转：T12 Unlock；
  - 闭合/拉链：T19 ZipUp、T31 OrganizePencilCase；
  - 释放/滑移：T27 StackBowls、T01 HangCup；
  - 开盖/倾倒：T14 PourOutMedicine。
- 判定：PRL 近成功转化率 ≥20%、误触发 <5%/episode、无安全/超时回归；否则回退。

### 11.4 正式跑

- 计划 2 次：W7 中期、W8 终期；若只允许 1 次，W8 唯一一次。
- 提交前 4h soak：N 端口并发、独立 reset/history、健康检查、延迟 p99；FLEET 检查单。
- 统计：320 trials；单臂 SE≈2.56pp；两臂独立 +3pp 功效≈13%、+5pp≈27%；强配对 +3pp≈21–32%、+5pp≈48–69%。**正式跑只押 +10pp 量级的强干预**；小效应用调试槽/离线。
- 报告：成功率 + 95% CI；步骤分作为 tie-break 诊断；每任务每步完成率；延迟 p50/p99；恢复/误触发。

### 11.5 指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 成功率 | 全步骤完成 | 主指标 |
| 步骤分 | 官方部分分 | tie-break/诊断 |
| 近成功转化率 | 终局前失败→成功 | ≥20% |
| 恢复成功率 | 触发恢复后完成当前步 | ≥50% |
| 误触发率 | 错误中断/episode | <5% |
| 不可行动作率 | OHKS 拒绝/投影比例 | <1% |
| 碰撞/超时 | 安全/时间 | 0 安全；超时 <5% |
| 延迟 | get_action p50/p99 | p99 <200ms |

## 15. 创新点清单（持续迭代；动机/差异/可行性/资源/步骤/风险/状态）

> 状态：押注=本轮主线；保留=沿用；升级=旧点被改造；降级=保留但不再是主回路；砍=不做。

### I1 PRL 本体反射层（新增，押注）
- 动机：VLA chunk 开环；接触/卡死/滑移/扰动是身体级失败；API 有本体但无扭矩。
- 差异：不学大世界模型；用动作−状态残差 + 有限差分 + URDF 期望运动；输出事件/恢复，不只是中止；可包在任意 VLA 外。
- 可行性：CPU <5ms；阈值版无需训练；学习头 <1M 参数。
- 资源：1–2 人周；演示回放 + 注入扰动；无额外数据。
- 步骤：信号→事件→恢复原语→标定→调试槽→学习头。
- 风险：误触发/无扭矩/滑移需视觉；高置信才中断。
- 状态：**押注**。

### I2 OHKS 开源运动学影子（新增，押注）
- 动机：VLA 不知道限位/自碰撞/桌面/可达性；EE 位姿可能无效；API 缺 torso EE。
- 差异：确定性 URDF，不是第二个模型；动作投影 + 可达放置 + Dex1 几何。
- 可行性：Pinocchio/MuJoCo；FK 1ms/IK 5ms；G1 URDF 公开。
- 资源：1–2 人周；无额外数据。
- 步骤：解析 URDF→FK 校验→IK→限位/碰撞→投影→训练标签。
- 风险：URDF 失配；软约束/margin；演示回放校验。
- 状态：**押注**。

### I3 SMSG 立体米制槽位（新增，支撑）
- 动机：API 无深度；放置/插入需要米制；头戴立体对已标定。
- 差异：经典 SGBM（合规），不是学习模型；关键帧异步；与 OVPL mask 融合。
- 可行性：基线 58.25mm、fx≈282；0.3–0.8m 深度 5.5–38.9mm/px。
- 资源：2–3 人周；相机标定/外参；CPU/GPU 少量。
- 步骤：验证相机对→校正→SGBM→容器/槽位→外参→回退。
- 风险：透明/无纹理/外参；单目回退；只做粗槽位。
- 状态：**支撑/押注**。

### I4 OVPL 开放词汇蒸馏（新增，支撑）
- 动机：未见物品轴；推理不能挂第二个模型；33k 演示可离线打标。
- 差异：教师只在离线；学生辅助头在同一 checkpoint；开放词汇能力蒸馏而非部署。
- 可行性：Grounding DINO/SAM3/DINOv3/SAM3D 现成；抽样 2–6 万帧。
- 资源：8×H100 4–6 天；人工抽检；许可核对。
- 步骤：标签 schema→教师打标→一致性→辅助头→蒸馏→离线评测。
- 风险：标签噪声/许可/规则；小权重/人工抽检/默认内部使用。
- 状态：**支撑**。

### I5 PPR 本体相位检索（新增，升级 ICR）
- 动机：视觉/语言键抗不了背景/外观；运动签名描述“正在做什么”。
- 差异：本体运动键 + 相位对齐 + 与 ICR 融合；库是数据，不是模型。
- 可行性：HNSW <5ms；缓存编码；K=1–4。
- 资源：1–2 人周；复用 ICR 基础设施。
- 步骤：切段→签名→索引→融合→延迟压测。
- 风险：速度/任务多解；分桶/语言约束。
- 状态：**升级**。

- 状态：**保留/修正**。

### I9 SVL 释放校验（保留，升级）

- 资源：1–2 人周。
- 步骤：稳定性检测→修复库→预算→接线。
