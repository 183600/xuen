## 0. 本轮研究日志（RUBICON 3.0/4.1 → 5.0 PHOENIX）

> 本轮随机词：**行为克隆、开源硬件、意图识别**。检索日期：2026-10-23。所有外部信息在产物区 J 节列链接；无法核实的地方明确标“未核实”。

### 0.1 我先做了什么（而不是先写方案）

1. 重新抓了主页、挑战页、排行榜、runs、GitHub `unibot_submission`、HF collection、Feishu 中英文手册、UnifoLM-WLA/unitree_lerobot 文档。

### 0.2 四个会改变方案的硬事实

**事实 A：榜单仍是随机占位，29.7% 不能当真实榜首。**  
主页仍写 “Coming Soon”；直接请求 `leaderboard.html` 被 EdgeOne 567 拦截；`r.jina.ai` 渲染出的 8 行表（MolmoAct/DexHacker 29.7% 等）与上一轮审计的随机占位脚本一致。结论：可以分析命名模型的论文，不能引用分数；用户简报里的“榜首 <30%”只能当难度直觉，不能当证据。

**事实 B：运行时接口比“VLA 论文里的理想输入”窄得多。**  
只有 4 路 RGB（左右 high + 左右 wrist）、双臂 7+7、EE pose 6+6、gripper 1+1、`lower_body[15]`、一个 `language` 字符串；没有 depth、没有 camera intrinsics/extrinsics、没有 `state_torso`/`waist_state_joint`。动作只收 `joint` 或 `ee`（二选一）+ 双 gripper + `pivot[7]`；`action_chunk_size` 可配；N 个端口从 8765 连续暴露。  
→ 任何依赖绝对深度、在线分割、多模型级联的方案都要重写；部件 3D 只能靠**数据集标定先验 + 运行时自标定双目/相对几何**。

**事实 C：公开数据是成功演示，官方干扰是“语义状态改变”。**  
32 任务约 33.3k episodes / 169h，4 路相机，30fps，5 条英文复述；数据里没有 failure/recovery/force 标签。官方 `human_1/human_4` 不是“手挡一下”，而是撤销（T10/T12/T14/T16/T17/T19/T27）、重置（T24）、移除（T12/T28/T29）、移动底座/架子（T08/T11/T21/T25）、阻塞（T05/T26）。  
→ 纯 BC 的“进度单调递增”假设在评测时被直接打破；这是本轮的主战场。

**事实 D：WLA-1.0-Base 是 obvious baseline，不是差异化。**  
Unitree 自家 6B、约 2,500h 真机、64 任务、G1、Apache-2.0，且官方开放了 UniBot 数据与 action-expert 微调代码；冻结 VLM、只训 DiT action head + state projector，默认单卡 24GB 可跑。强队大概率都会用它或同级底座。  
→ 不能把“用上 WLA”当创新；创新必须在**数据配方、恢复模式、意图状态、评测基础设施**上。

### 0.3 行为克隆：最大的漏洞不是模型太小，而是“只学成功、不会回头”

BC 在演示分布上最小化 `-log π(a|o)`；评测时 human undo 把状态推到演示分布之外。标准 BC 没有“回到之前子目标”的训练信号，误差会复合。2026 年的几条线已经把这个问题独立出来：

- **ReTVL**（2606.24633）：把 retry 事件当稀疏监督，学“局部退化—恢复”的价值函数，再对 BC chunk 重加权。
- **ALIGN**（2610.26455）：在混合质量数据上做 advantage-conditioned BC，把 retry/recovery 条件注入 DiT action expert。
- **GR-BC**（2610.20504）：在演示+干预 rollout 上建 goal-reachability graph，用“到目标的最短剩余步数”给 chunk 重加权；干预轨迹被当作恢复路径。
- **PARS**（2609.33049）：只扰动 proprio，锚定轨迹后半段，不需要新数据就能训“从扰动状态回到演示”的恢复。
- **AFIL**（2605.08434）/ **Kintsugi-VLA**（2609.31048）：用失败 rollout / 仿真状态恢复生成 recovery data；后者证明 recovery 是独立维度，且“干净任务成功率”可能只掉 2pp。
- **EgoRecovery**（2607.19745）：人类恢复演示 + recovery gate，数据效率比机器人遥操作高 10 倍。
- **RoboRecover**（2609.28952）：初始状态成功率不能预测恢复成功率；恢复需要“推断进度变化、修正关系、继续原目标”。

**空位**：这些工作大多假设有仿真器、失败 rollout、人类干预数据或力/深度；UniBot 的公开数据只有成功演示，运行时没有 depth/force，官方又不允许混合多模型。我们的切入点是：**用成功演示 + 合成扰动 + 反事实撤销 + 小规模开源硬件恢复数据，训一个“恢复模式”在同一个 checkpoint 里**。这不是“再大一点的 VLA”，而是把 BC 的分布支撑补到评测分布上。

### 0.4 开源硬件：不是买一台 G1，而是把“评测/干预协议”复制出来

如果直接买 G1，成本高、周期长，而且官方评测机器人不一定允许改硬件。更划算的是 **ORT（Open Recovery Testbed）**：

- **范围**：只做 14 个受人为干扰影响最大的任务（8 个 undo + 6 个 move/remove/block），不做全 32 任务复制。
- **硬件**：桌面 + 4 路相机（头部双目 ~60mm baseline + 左右腕）+ 3D 打印夹具/货架/传送带/插座/锁/笔盒/试管架；机械臂优先 G1，退而求其次用双 SO-101 或单臂 + 固定底座。
- **协议**：先由人遥操作到子目标完成；第二个人/脚本臂在最后 30% 随机执行 undo/move/remove/block；第一个人恢复并完成；全程录 4 路视频 + proprio + action + 干预标签。
- **用途**：(1) 真实恢复数据；(2) 本地 10-trial LPL；(3) 意图状态标签；(4) 可选 OpenTac 触觉教师。
- **不做**：全 32 任务复制；为评测机器人加传感器；把 SO-101 的动作直接克隆到 G1（只做表征/门控/意图，不做动作克隆）。

开源硬件在这里不是“省钱的玩具”，而是**把官方 20% 的人为干扰 trial 变成可反复采样的数据源**。这是别人不容易复制的地方。

### 0.5 意图识别：两层可验证的意图，不做读心

“意图识别”在本赛可以拆成两层，都是可观测、可标注的：

1. **任务目标意图（Goal Intent）**：语言 → 目标谓词集合。比如 “put all fruits into the basket” → `forall(fruit): in(fruit, basket)`；“zip up the pouch” → `closed(zipper) & upright(pouch)`。用离线 LLM 编译 + 运行时小文本编码器/对比匹配，不跑在线 LLM。
2. **干预效果意图（Intervention Effect）**：场景变化 → `relocate / undo / remove / block / distract`。这不是猜人心，而是从 1–2 秒的视频窗口和部件状态变化分类“人做了什么”。官方备注给了天然标签体系。

两者统一成一个 **Intent-State Head (ISH)**，输出 6 个策略状态：
`on_track / local_error / subgoal_undone / goal_satisfied / unrecoverable / blocked`。
运行时用**部件状态预测误差 / chunk disagreement** 触发重评估；ISH 决定 `continue / repair / re-scan / wait / stop`。这比标量进度头更适合官方干扰，因为“毛巾被翻开”不是“进度 60%”，而是“fold_1 从 true 变 false”。

### 0.6 主押注：RUBICON 5.0 / PHOENIX

> **PHOENIX = 用恢复数据把 BC 的分布支撑补到评测分布上，用意图状态头在运行时决定继续/修复/等待/停止。**

- **P0-1 Phoenix-BC**：retry mining + PARS 扰动 + 反事实撤销重标注 + GR-BC 式 chunk 重加权 + ORT 真实恢复共训。目标是在 8 个 undo 任务上把 human trial 从 0–10% 抬到 30–50%，并顺带提升 nominal。
- **P0-2 ISH**：6 状态意图 + 5 类干预效果 + goal satisfaction；同一 checkpoint 的多任务头；预测误差触发；滞回/校准。
- **P0-3 ORT**：14 任务开源硬件测试台；200–500 条恢复 episode；本地 LPL。
- **P1 SPA-lite**：部件 2D keypoint + 双目相对深度 + 离线 SAM3 教师；不做运行时分割模型。
- **P1 RPSM 2.0**：12 个部件谓词 + 可逆 belief + 最小修复；与 ISH/Phoenix-BC 共用特征。
- **P1 Compliance / Endurance / Portfolio**：防归零、N 端口/p99/4h soak、按成功率口径分配预算。
- **P2 Tactile-to-Vision / GIC / 双目自标定 / 跨 embodiment 恢复预训练**。
- **P3 世界模型/MPC**：只做离线教师/表征蒸馏，不做在线 14B。

### 0.8 修剪/暂缓（本轮明确不做）

- **全量 32 任务开源硬件复制**：时间不够；只做 14 个干预任务。
- **运行时 SAM3/PartSAM 级联**：违反“单模型”风险；只做离线教师。
- **在线 14B world model / 视频扩散**：算力/延迟/无 depth，不划算。
- **全量 TAMP/PDDL 在线规划**：延迟/任务特定风险；只保留谓词图最小修复。
- **在线 RL / residual RL**：样本效率/安全/时间不允许；用离线重加权替代。
- **任务特定硬编码轨迹/坐标**：泛化差、可能违规；只用语言 + 部件谓词 + 通用技能。
- **为评测机器人加触觉/深度**：硬件不由我们控制；触觉只做离线教师。
- **把 SO-101 动作直接克隆到 G1**：形态差距大；只做表征/门控/意图。
- **“再大一点的 VLA”**：边际收益不在参数规模，而在恢复数据与状态接口。

### 0.9 为什么这版可能赢（可证伪的账）

- 官方排序是**总平均成功率**；人为干扰占每任务 2/10 trial。14 个干预任务里，若 human trial 从 0→30%，总平均 +2.6pp；从 0→50%，+4.4pp。
- 若恢复能力同时把 14 个任务的 nominal（8/10 trial）抬 5–10pp，再 +1.8–3.5pp。
- 合计目标：乐观 **+4.5–8pp**，base case 约 **+2.5–4.5pp**；在 320 trial、p≈0.3 时 SE≈2.6pp，前者可检测，后者需要配对/更多 trial。
- 成本：不需要从零训大模型；WLA action-expert 微调单卡 24GB 可跑；ORT 用商品件 + 3D 打印，1–2 万元级；8 周可完成 MVP。
- 风险：合成撤销不真实、retry 标签噪声、ORT 形态差距、ISH 误报。都有对应的消融/回退路径（见产物区 F/H）。

## A. 结论

本轮在 RUBICON 3.0/4.1 的基础上升级为 **RUBICON 5.0 / PHOENIX**。核心判断是：

> **UniBot 的隐藏瓶颈不是“语义泛化不够”，而是“成功演示的行为克隆不会处理非单调状态”。** 官方 `human_1/human_4` 大量是撤销已完成子目标；公开数据只有成功轨迹；运行时没有 depth/force；单模型规则又不允许在线级联分割/世界模型。因此，最高 ROI 的创新不是再训一个更大的 VLA，而是**把恢复能力做进同一个 checkpoint**：用成功演示 + 合成扰动 + 反事实撤销 + 小规模开源硬件恢复数据，训练一个“恢复模式”；再用**意图状态头**在运行时决定继续/修复/等待/停止。

三条灵感词的落点：

1. **行为克隆 → Phoenix-BC**：retry mining、PARS 扰动、反事实撤销重标注、GR-BC 式 chunk 重加权、ORT 真实恢复共训。它直接补 BC 的分布支撑，而不是换一个更大的底座。
2. **开源硬件 → ORT（Open Recovery Testbed）**：14 任务（8 undo + 6 move/remove/block）的低成本物理复制 + 脚本化干预协议 + LeRobot/Unitree 数据栈；用于恢复数据、本地 LPL、意图标签；不做全 32 任务复制，不为评测机器人加传感器。
3. **意图识别 → ISH（Intent-State Head）**：两层可验证意图——任务目标意图（语言→目标谓词）和干预效果意图（场景变化→undo/remove/relocate/block）；输出 6 个策略状态，驱动 continue/repair/re-scan/wait/stop。不做读心。

**与上一版的关键变化**：

| 3.0 / 4.1 | 5.0 / PHOENIX | 原因 |
|---|---|---|
| SPA-VLA 作为主押注，默认部件 3D centroid 来自深度 | SPA-lite 降为 P1；2D keypoint + 双目相对深度 + 离线 SAM3 教师 | 运行时没有 depth/camera params；单模型规则不允许在线分割级联 |
| RPSM 作为独立运行时记忆 | RPSM 2.0 融入 Phoenix-BC/ISH；训练时学修复，运行时只做触发与最小修复 | 只靠运行时 prompt 不能教会策略“怎么修” |
| PPSC-S 的 chunk 级 MPC/异步验证 | 降为 P3；只保留小 dynamics head 做预测误差触发 | 无 depth/force、延迟预算紧、收益不确定 |
| “先修 0% 任务 + 组合优化” | 保留，但把“干预任务”作为最高优先级桶 | 人为干扰占 20% trial，且 14 个任务直接受影响 |
| Compliance/Endurance/Portfolio 分散 | 压缩成 P1 的三个运行时门禁 | 防归零与部署稳定性仍是硬约束，但不是主战场 |
| 用公开榜 29.7% 做难度直觉 | 明确：公开榜仍是随机占位，不能当证据 | 主页 Coming Soon；直接请求被 EdgeOne 567；渲染表与随机占位一致 |

以下事实以 **2026-10-23** 可访问的公开页面/文件为准；无法核实处标“未核实”。

## B. 已核实事实

### B.1 官方规则（已读部分）

| 维度 | 规则 | 来源 | 对策略的影响 |
|---|---|---|---|
| 赛道 | 仅通才模型（Multi-task）赛道；单任务测试通道不计分 | Feishu 1.2 | 必须 32 任务整体可用 |
| 模型 | **所有任务须基于同一模型完成，不得混合多个模型一起测试**；模型类型不限（World Model、VLA 均可） | Feishu 1.1 | 不做“分割模型 + VLA”的在线级联；教师只离线；恢复模式/意图头必须在同一 checkpoint |
| 试验 | 每任务 10 次独立运行 | Feishu 1.2 / 2.1 | 每任务只有 10 个 Bernoulli 样本 |
| 泛化 | 5 类：位置、干扰物、桌面背景、未见物品、人为干扰；每类 2 次 | Feishu 2.1 | 人为干扰恰好占 2/10 trial；必须单独建桶评估 |
| 时限 | 单次真机最多 **180 秒**；超时记失败，但仍按执行情况给步骤分 | Feishu 2.1 | 需要阶段预算、watchdog、超时前安全退出 |
| 排名 | 32 任务**总平均成功率**降序；相同则**总平均步骤分**降序；再相同则**提交日期早**者靠前 | Feishu 1.2 | 成功率第一；步骤分只在平分时有用 |
| 部署 | 选手自行部署推理服务；平台远程 API 调用；平台不提供算力 | Feishu 1.1 | N 端口、并发、p99、热/内存/崩溃是硬约束 |
| 端口 | N 台机器人；从 `8765` 起连续 N 个端口（`8765 … 8765+N−1`）；端口数必须恰好等于 N；随机顺序评测；每端口独立 reset/状态隔离 | README §5 | 不能假设单机器人；不能依赖任务顺序 |
| 交互质量 | 每步延迟、延迟波动、动作统计规律会被记录，并可能与成绩一起展示 | README §6 | 延迟抖动/异常动作会损害可信度 |

**未核实**（不能写成确定规则）：

- 外部数据/预训练模型是否允许；许可证要求。
- N 的具体值；控制频率；动作数值范围/裁剪。
- 4.2 评分公式细节；4.3 排名/入围/成绩记录细节。
- 任务硬编码限制；base/waist 限制；评测是否把 task id 传给模型。

5. **交互质量**：p99 延迟、动作平滑/限幅、无 NaN/离群；4h soak 是硬需求。

### B.3.6 标定/几何事实（决定“无 depth”方案）

- 32 任务至少 **10 组**头部双目标定；`fx` 约 186–296，baseline 约 **46.7–64.9mm**，`cx` 左 302–365 / 右 316–384。不能全局硬套一组外参；按任务读 `camera_params`，运行时用相对几何/自标定。
- G1 头部双目 fB≈16.45 m·px：1m 处 0.1px 视差误差 ≈ **6.1mm**；0.5m 处 ≈ **1.5–2.5mm**。头部 stereo 只能做厘米级粗定位；接触最后几毫米必须靠**腕部近景 + 相对位姿**。
- `pivot_3≈waist yaw`（r≈0.73）、`pivot_4≈waist pitch`（r≈0.86）、`pivot_5=0`；多数任务 pivot 近静态，OrganizeTools 连续用 waist，FoldTowel/StorePaddle 有回合级偏移。不要为了“用上 pivot”乱动下身；按任务配置，默认保持。
- 头部在 OrganizeTools 中 pitch/yaw std≈0.09/0.08，HangCup≈0.014–0.019；头部会动，part 3D 不能假设固定外参。
- **结论**：不用绝对 3D centroid；用 2D keypoint + 双目相对视差 + 腕部近景 + 每任务标定先验。SPA-lite 的设计依据在这里。

## C. 失效分析与收益模型

### C.1 评测结构

每个任务 10 次 = 5 类泛化 × 2 次；32 任务共 **320 次 trial**。成功率是 320 个 Bernoulli 的平均，单任务只有 10 个样本。任何“单任务 +20%”的说法都必须带置信区间；否则只是噪声。

步骤分的两个作用：

1. 失败但部分完成时给部分分（Feishu 2.1：超时仍按执行情况给分）。
2. 总平均成功率打平时，用总平均步骤分破平（Feishu 1.2）。

因此策略优先级是：**先避免 0% 任务，再提高平均成功率，最后才优化步骤分/速度**。不要为了“更快”牺牲成功率。

### C.2 失效桶（best-effort，待 E0 校准）

下表是“在没有恢复机制时，320 次 trial 中最可能失败的机制”。数字是假设，不是测量；E0 必须用本地 32 任务 rollout + ORT 替换。

| 桶 | 典型任务 | 假设失败/trial | 占失败 | 机制 | 对应处理 | 预期任务级 Δ |
|---|---|---:|---:|---|---|---:|
| B1 抓取/接触失败 | HangCup、PackPhone、StorePaddle、ToolboxStorage、SortScrew | 35–55 | ~18% | 抓空、滑移、夹爪闭合时机错、物体位姿偏移 | Phoenix-BC retry 数据 + 腕部近景 + 夹爪闭环 | +3–6pp |
| B2 长程未完成/超时 | FoldTowel、ZipUp、SpellRobot、PackPhone、StorePaddle、HangCup | 40–60 | ~20% | 子目标顺序错、重复动作、在 180s 内做不完 | part-state 记忆 + 阶段预算 + 恢复模式 | +3–8pp |
| B3 精度/插入/对齐 | ZipUp、StorePaddle、PackPhone、SortScrew | 25–40 | ~12% | 拉链/插孔/对位需要 <5mm 精度；无 depth/force | 双目相对深度 + 腕部视觉伺服 + 小步修正 | +2–5pp |
| B4 语义/OOD | 未见物品、背景变化、位置变化 | 30–50 | ~15% | 语言-目标 grounding 不稳；背景/光照偏移 | 5 条复述对比学习 + 背景增强 + 目标谓词头 | +2–5pp |
| B5 人为干扰/撤销 | 14 个任务（8 undo + 6 move/remove/block） | 40–80 | ~25% | 已完成子目标被撤销；策略继续原计划，不检测/不修复 | **Phoenix-BC + ISH + ORT（本轮主押注）** | +5–12pp |
| B6 服务/动作异常 | 全部 | 5–15 | ~5% | 延迟尖峰、NaN、动作越界、端口串状态、重连丢 token | dispatcher + 限幅/平滑 + watchdog + 4h soak | 防归零 |

> 失败桶有重叠：一个 trial 可能既超时又抓取失败。上表用于排序，不用于精确分解。

**为什么 B5 是最高优先级**：

- 它占 20% 的 trial（2/10 人为干扰），且影响 14/32 任务（假设）。
- 公开数据是成功-only，BC 没有“撤销后怎么办”的监督；这是**分布支撑缺口**，不是容量缺口。
- 官方干扰很可能是“撤销已完成子目标”（用户简报反复出现 undo；需 E0/规则核实），这恰好可以用“反事实撤销”低成本合成。
- 现有基线（WLA/pi0.5/GR00T）主要优化 nominal 成功率，不显式建模恢复；这是差异化空间。

### C.3 收益模型

定义任务 \(i\) 的基线成功率 \(p_i^0\)，有恢复机制后的成功率 \(p_i\)，人类/脚本恢复后的上界 \(p_i^{H}\)，检测-修复覆盖率 \(q_i\)：

\[
p_i = p_i^0 + (1-p_i^0)\,q_i\,r_i,\qquad
r_i = \frac{p_i^{H}-p_i^0}{1-p_i^0}
\]

其中 \(r_i\) 是“在基线失败的 trial 中，人类恢复能救回的比例”。总平均成功率：

\[
S = \frac{1}{32}\sum_{i=1}^{32} p_i,\qquad
\Delta S = \frac{1}{32}\sum_{i=1}^{32}(1-p_i^0)\,q_i\,r_i
\]

**三个场景**（假设 8 个 undo 任务、6 个其他干扰任务、18 个 nominal 任务）：

| 场景 | 8 undo 每任务 Δ | 6 其他干扰每任务 Δ | 18 nominal 每任务 Δ | 总 ΔS | 解释 |
|---|---:|---:|---:|---:|---|
| 保守 | +2pp | +1pp | +0.5pp | **+0.97pp** | 只检测到部分干扰，修复动作不完整 |
| 基准 | +5pp | +3pp | +1pp | **+2.38pp** | 恢复数据有效，但 q≈0.5 |
| 乐观 | +10pp | +5pp | +2pp | **+4.56pp** | q≈0.8，且 undo 数据覆盖好 |
| 上界（IDEA 的 stretch） | +15pp | +8pp | +3pp | **+6.94pp** | 接近人类恢复上界；需要 ORT 全量 + 调参 |

> IDEA 草稿里的 “+4.5–8pp” 是乐观上界；按 320 trial 的统计噪声和 q 的折扣，**base case 更可能是 +2.5–4.5pp**，乐观 +5–7pp。这仍然值得做：在 25–30% 区间，+3pp 就是 10–12% 的相对提升。

**统计功效**：

- 320 trial、p≈0.28 时，\(\mathrm{SE}=\sqrt{0.28\times0.72/320}\approx 2.51\)pp。
- +3pp ≈ 1.2 SE（单侧 p≈0.12）；+5pp ≈ 2.0 SE（单侧 p≈0.023）。
- 本地 A/B 想可靠区分 +3pp，需要约 640 trial/组；或者用配对设计（同一初始状态，开/关恢复）降低方差。ORT 的价值之一就是能做配对实验。

**步骤分/时间的账**：

- 长任务（ToolboxStorage 37.6s、StorePaddle 34.1s、SpellRobot 31.2s、PackPhone 29.2s）在 180s 内通常够，但“重复尝试/恢复”会吃掉时间。
- 恢复模式的阶段预算：每个 part 分配 `remaining_time * (1 / remaining_parts)`，留 20% 余量；超过预算就进入“安全完成/停止”，避免超时 0 分。
- 步骤分只在成功率打平时用；不要把优化目标改成“更快”。

### C.4 什么会改变我们的判断

| 观察 | 如果为真 | 行动 |
|---|---|---|
| E0 发现人为干扰不是 undo，而是“加新物体/换目标” | 反事实撤销数据价值下降 | 把 ORT 的 relocate/block/remove 提到主位；undo 降为辅助 |
| WLA 基线已经能处理 retry（E1 显示 retry 数据无增益） | retry mining 不是瓶颈 | 把预算转到 ISH 检测 + 精度（B3） |
| 延迟预算 <100ms/chunk | 双前向/图门控不可行 | 砍 D6；ISH 只保留单头 + 规则 |
| N ≥ 8 或并发很高 | 服务成为瓶颈 | 优先 dispatcher/batching/FP8；策略简化 |
| 外部数据/模型被禁止 | 大教师不可用 | 只用挑战数据 + 自蒸馏 + ORT |
| 单模型规则把辅助头也算“多模型” | 架构不合规 | 所有头共享 backbone；语言解析离线；提交前问官方 |

### D.1 观测适配器

**输入**：4 路 RGB（头部左/右、腕部左/右）+ 双臂/夹爪/`lower_body` + 语言。**没有** depth、外参、torso、D435。

处理顺序：

1. **颜色/尺寸**：保持 480×640；训练用 RandomResizedCrop(0.8–1.0) + ColorJitter(0.2) + 随机擦除（小概率），模拟背景/光照/遮挡。
2. **头部双目相对深度**：
   - 离线：从数据集 `camera_params` 读每任务头部双目内参/畸变/R/T，做 rectify + StereoSGBM/RAFT-Stereo 教师，生成粗深度；训练一个轻量 depth head（或直接把 3 通道视差图拼到 RGB）。
   - 运行时：用同一 SGBM/轻量网络算视差；只取任务相关区域的相对深度（抓取点、容器口、桌面平面），不做绝对 3D 重建。
   - 不用 SAM3/分割大模型在线跑；目标区域由腕部近景 + part-state 的物体 slot 提供。
3. **腕部近景**：左右腕各裁 224×224 中心区域，单独过一个小 ConvNeXt/ResNet 分支（或共享 VLM 的 patch embed），输出接触/对齐特征；与头部 token 拼接。
4. **语言**：5 条复述分别编码，取平均 + 每条保留一个 token（5 个 token），用对比学习拉近同任务复述、推远不同任务；运行时只给一条，但训练时随机采样一条，避免过拟合到固定句式。
5. **状态**：`left_arm/right_arm[7]`、`left_ee/right_ee[6]`、gripper[1]、`lower_body[15]`；不做归一化以外的复杂编码；缺失项用 mask + learned token。
6. **动作历史**：最近 2 个 chunk 的动作（可选），用于平滑和检测“卡住”；不把历史当世界模型。

**为什么不用 3D centroid**：评测端没有 depth/标定；强行用数据集外参会 overfit 到训练桌。用相对视差 + 腕部近景更稳。

### D.2 骨干与动作空间

**默认底座：UnifoLM-WLA-1.0-Base（6B, Apache-2.0）**。

- 冻结 WLA 自带 VLM；训练 DiT action expert + state projector；单卡 24GB 可跑（bf16 + gradient checkpointing + LoRA 可选；具体 VLM 家族以 WLA 文档为准）。
- 统一 action 54-D：相对 EE（左右各 6）+ gripper（2）+ waist/torso（6）+ base（3）+ legs（12）+ 预留；带 validity mask。
- 统一 state 60-D + mask；训练时可多用，评测时只填可用子集。
- 30-step chunk @30fps；推理时一次出 chunk，server 按索引执行。

**动作空间选择**：

| 选项 | 优点 | 风险 | 建议 |
|---|---|---|---|
| `ee`（官方） | 与 WLA 相对 EE 最接近；对关节误差不敏感 | 需要相对→绝对桥接；IK/限位 | **默认** |
| `joint`（官方） | 直接给关节目标；无 IK 误差 | WLA 的 joint 头未在 UniBot 上验证；不同机器人关节顺序 | 备选/对照 |

**相对→绝对桥接**（D.7 详述）：WLA 输出 \(\Delta ee\)，运行时用当前 `observation.state.left_ee_pose_gripper_base` 组合得到绝对目标；限幅到工作空间；再发给 server。不要把 WLA 的 54-D 直接截断成官方 6-D。

**备选底座**：

- π0.5 / GR00T N1.6：如果允许且显存够；它们的跨 embodiment 先验更强，但 UniBot 微调成本更高。
- 自研 3.5B：只作为“如果 WLA 不可用”的 fallback；不在主计划里。

**合规性**：所有头共享同一个 VLM/DiT backbone；不是“分割模型 + VLA”两个模型。语言解析在初始化时离线完成（或用一个共享 embedding 的轻量头），运行时只有一个 checkpoint 在推理。

### D.3 Phoenix-BC 数据管线

目标：把“成功-only 演示”变成“含局部失败、撤销、恢复”的训练集，且**不改变评测输入**。

#### D.3.1 Part-State Graph（PSG）

对每个任务手工定义 3–8 个 part（子目标/物体状态），例如：

| 任务 | parts |
|---|---|
| HangCup | `cup_grasped → cup_lifted → cup_hung → released` |
| FoldTowel | `towel_flat → left_fold → right_fold → folded` |
| ZipUp | `zipper_engaged → slider_started → zipped` |
| ToolboxStorage | `tool_grasped → tool_moved → tool_in_box → lid_closed` |
| PackPhone | `phone_grasped → phone_in_box → box_closed` |

标注方式：

- 规则/脚本：用物体 6D/2D 轨迹 + gripper 状态 + 接触启发式，自动提候选区间；人工抽检 10%。
- 视觉教师：SAM3/ GroundingDINO 离线跑关键帧，生成物体 mask/框；只用于标注，不进运行时。
- 每个 part 有 `start/end` 帧、`precondition`、`effect`、`undoable` 标志。

**规模**：32 任务 × 3–8 parts ≈ 150–250 个 part 区间；每任务抽 20–50 episodes 做 part 标注，共 1,000–1,500 episodes，人工 2–3 天。

#### D.3.2 Retry Mining

在 PSG 上定义 retry：

- 同一 part 的 `start` 出现 ≥2 次，且中间没有进入下一个 part；
- 或 gripper 开合序列出现“闭合→张开→再闭合”且物体位姿未变；
- 或末端轨迹在局部区域来回（速度反向 ≥2 次）且 part 未完成。

输出：`(t_retry_start, t_retry_end, part_id, outcome)`。只保留“最终成功”的 retry 段作为正样本；失败段（如果数据集里有）作为负样本。

**注意**：gripper 切换 ≠ retry（多物体任务会正常切换）。必须用 part 区间约束，否则会把正常子目标误标成 retry。这是 B.3 抽查表的核心 caveat。

#### D.3.3 PARS 扰动（零新数据）

对每个成功 chunk：

\[
\tilde a_t = a_t + \epsilon_t,\quad \epsilon_t \sim \mathcal N(0,\sigma^2),\quad
\mathcal L_{\text{PARS}} = \|\pi(o_t,l,z_t)-a_t\|^2 + \lambda\|\pi(\tilde o_t,l,z_t)-a_t\|^2
\]

其中 \(\tilde o_t\) 是用扰动动作执行后的观测（离线用数据集相邻帧近似，或用轻量 dynamics 模型预测；ORT 上可真执行）。\(\sigma\) 按关节/EE 维度缩放（EE 位置 5mm、旋转 0.02rad、gripper 0.05）。

作用：让策略在“稍微偏了”的状态下仍能回到原动作，而不是继续漂移。成本：零新数据；风险：扰动太大时目标动作不再可达，需按 part 阶段调 \(\sigma\)。

#### D.3.4 反事实撤销（Counterfactual Undo）

对每个 `undoable` part \(p\)，在成功轨迹中取：

- \(t_g(p)\)：part 开始前的 pre-grasp/approach 状态；
- \(t_p\)：part 完成后的状态；
- \(t_r\)：part 之后、下一 part 之前的释放/离开状态。

构造两条样本：

1. **undo 样本**：观测 = \(o_{t_p}\)（已完成）+ 语言“undo \(p\)”/“put it back”；动作目标 = 从 \(t_p\) 回到 \(t_g(p)\) 的逆轨迹（用 \(t_g..t_p\) 的动作反转/重放，末端加释放）。
2. **re-do 样本**：观测 = 撤销后的 \(o_{t_g}\)；动作目标 = 原子轨迹 \(a_{t_g..t_p}\)；标签 = “recover \(p\)”。

关键：**只在训练时合成观测**（把 \(o_{t_p}\) 和 \(o_{t_g}\) 拼接/重放），不需要真机；ORT 上验证物理可行性。这样 BC 第一次看到“子目标被撤销”的输入分布。

#### D.3.5 GR-BC 式重加权

用 PSG 建 DAG：节点 = part 状态，边 = 原子段；边权 = 该段平均步数。对每个训练帧，算“到目标的剩余最短步数” \(d(s_t)\)；权重：

\[
w_t = \exp\!\left(-\alpha\,\frac{d(s_t)-d_{\min}}{d_{\max}-d_{\min}}\right)
\cdot
\begin{cases}
1+\beta, & \text{retry/recovery 段}\\
1, & \text{nominal}
\end{cases}
\]

- \(\alpha=0.5,\beta=1.0\) 起步；在验证集上扫。
- 作用：让“接近目标但还没完成”的帧权重更高；让 retry/恢复段不被大量 nominal 帧淹没。
- 与 ReTVL 的 retry-value 重加权同源；我们不学 value function，先用图距离，简单可解释。

#### D.3.6 ORT 共训

ORT 14 任务采 2–3 种恢复轨迹/任务（见 G.2），与公开数据按 **1:5 ~ 1:10** 混合（恢复样本重复采样）。ORT 数据只占 <15% 的 batch，避免过拟合小测试台。

#### D.3.7 负样本（AFIL 式）

从失败 rollout（ORT 上故意失败/扰动后不恢复）取状态，构造“不要执行的动作”或“失败前最后动作”的负样本；用对比/边距损失让策略远离。规模小（<5%），避免把“谨慎”学成“不动”。

#### D.3.8 混合配方（初始建议）

| 数据 | 比例 | 作用 |
|---|---:|---|
| 公开成功演示 | 55% | nominal 保真 |
| PARS 扰动 | 20% | 局部鲁棒 |
| 反事实撤销/re-do | 15% | 恢复模式 |
| ORT 真实恢复 | 8% | 物理校正 |
| AFIL 负样本 | 2% | 避开失败 |

训练时按任务均衡采样（每任务最多 2×平均），避免长任务/多 episode 任务主导。

### D.4 ISH：Intent-State Head

ISH 不是“读心”，是**可验证的两层意图**：

1. **任务目标意图**：语言 → 目标谓词 + 物体 slot + 空间关系。初始化时解析一次，存成结构化 prompt；训练时用 5 条复述做对比，让视觉-语言对齐。
2. **干预效果意图**：观测变化 → `undo / remove / relocate / block / distract`。这是“人做了什么”，不是“人为什么做”。

#### D.4.1 输出

| 头 | 类别 | 标签来源 | 用途 |
|---|---|---|---|
| Effect Head | 5 类：`undo, remove, relocate, block, none` | ORT 脚本 + 规则（物体位移/消失/新增/遮挡） | 决定修复算子 |
| State Head | 6 类：`on_track, local_error, subgoal_undone, goal_satisfied, unrecoverable, blocked` | PSG + 扰动 + 反事实 + 失败 rollout | 决定 continue/repair/wait/stop |
| Part-State Head | 32 任务 × K parts 的多标签 | PSG | 记忆已完成/未完成 |
| Recovery Value Head | 标量 \(v\in[0,1]\) | retry 段/恢复成功标签 | 触发修复的优先级 |

#### D.4.2 运行时逻辑

```
每 chunk：
  z = backbone(obs, language)
  part_state = PartStateHead(z)          # 多标签
  effect = EffectHead(z)                 # 5 类
  state = StateHead(z)                   # 6 类
  v = RecoveryValueHead(z)               # 标量

  if change_point_detected(obs, prev_obs):
      effect = argmax EffectHead
      update part_state with effect
      if state == subgoal_undone:
          repair = choose_repair(part_state, effect, graph)  # undo/re-do/relocate/remove
      elif state == blocked:
          repair = wait_or_remove
      elif state == unrecoverable:
          repair = stop
  else:
      repair = continue
```

**变化点检测**：对头部/腕部视觉 embedding 与 proprio 做 CUSUM：

\[
S_t = \max(0, S_{t-1} + \|e_t - \mu\|_2 - \kappa),\quad \text{trigger if } S_t > h
\]

- \(\mu\) 用 episode 前 1s 的滑动均值；\(\kappa=0.5\sigma\)，\(h=3\sigma\)。
- 触发后进入 3 帧确认，避免光照/遮挡误报。
- 触发频率天然稀疏（HINT 的观察：意图变化远少于控制步）。

**修复选择**：在 PSG 上枚举可达的修复算子，用“剩余步数 + 风险”打分：

\[
\text{score}(r) = -\hat d(s \xrightarrow{r} s_{\text{goal}}) - \lambda\,\text{risk}(r)
\]

`risk` 手工设：undo/re-do 低，remove 中，relocate 中高，stop 最高（但安全）。取 argmax；若无可行修复，`wait` 或 `stop`。

**wait 语义**：检测到人为干预但尚未结束时，保持安全位姿（双臂回收、夹爪张开/闭合按任务），每 0.5s 重扫；干预结束后重新分类，不要“边被推边继续”。

**stop 语义**：不可恢复/即将碰撞/超时前 10s，安全退出并保留步骤分；不要为了“可能救回”冒损坏风险。

#### D.4.3 训练标签与损失

\[
\mathcal L_{\text{ISH}} =
\lambda_e \text{CE}(\text{effect}) +
\lambda_s \text{CE}(\text{state}) +
\lambda_p \text{BCE}(\text{part}) +
\lambda_v \text{MSE}(v)
\]

- \(\lambda_e=0.5,\lambda_s=0.5,\lambda_p=0.3,\lambda_v=0.2\) 起步；与动作损失联合训练，动作损失权重 1.0。
- 标签不完美时用 label smoothing（0.1）和 class weights（undo/blocked 稀少，权重 3–5）。
- 不做“意图预测未来 N 步”的辅助任务；先把分类做准。

```
                    EXECUTE
```

**阶段预算**：每个 part 的预算 = `remaining_time × (1/remaining_parts) × 0.8`；剩余 20% 作为恢复/收尾余量。超预算 → 尝试最快完成/安全退出。

**watchdog**：每次请求 1s 无响应 → 返回 hold（当前关节保持/夹爪保持），记录；连续 3 次 → 安全退出。NaN/越界 → 同上。

### D.6 RPSM 2.0（Part-State Memory）

- 只存 `part_state`（32×K 布尔）、`effect` 历史（最近 3 次）、`v`、当前阶段预算；不存原始视频/大特征。
- 更新：每个 chunk 用 Part-State Head 覆盖/衰减；变化点触发时强制更新。
- 用途：动作条件的 `z_t`、修复选择、避免重复已完成子目标。
- 不在运行时跑图优化/搜索；图只在训练时用于重加权和修复选择表。
- 内存 <1MB/端口；与 N 端口隔离。

### D.7 动作桥接与安全

**相对 EE → 绝对 EE**：

\[
T_{\text{abs}}^{t+1} = T_{\text{abs}}^{t} \cdot \exp(\Delta \xi_t),\qquad
\Delta \xi_t = (\Delta p, \Delta r)
\]

- WLA 输出 \(\Delta p\)（米）、\(\Delta r\)（轴角/欧拉）；用 SE(3) exp 组合，避免欧拉奇异。
- 限幅：位置 ±2cm/chunk，旋转 ±0.1rad/chunk；工作空间盒（桌面 ±0.6m，高 0.02–0.8m）。
- 奇异/IK 失败 → 回退到 hold + 小步重试；不要发 NaN。

**夹爪**：连续值 → 二值开/合（阈值 0.5），加 2 帧滞回；抓取时闭合到目标开度（不是全力），避免顶飞物体。

**pivot[7]**：只发前 7 维；限幅 ±0.05rad/chunk；慢启动；如果不确定，保持当前值（不要乱动下身）。

**动作掩码**：只发 `left_arm/right_arm` 或 `left_ee/right_ee` 之一 + `left_gripper/right_gripper` + `pivot`；其他键不发。训练时的 `lower_body/base/waist/torso/d435` 只用于辅助损失/state，不进 server。

**平滑**：一阶低通 \(a_t = \alpha a_t + (1-\alpha)a_{t-1}\)，\(\alpha=0.7\)；chunk 边界重叠 2 步，线性混合。

### D.8 服务与部署

| 需求 | 设计 |
|---|---|
| N 端口 | 每端口一个 session；`port = 8765 + index`；随机顺序不共享可变状态 |
| 并发 | 全局 model singleton；dispatcher 微批（max 4，窗口 10ms）；每 session 串行 |
| 延迟 | 目标 p50 <120ms、p99 <300ms/chunk（30-step chunk 可覆盖 1s）；上线前测 |
| 显存 | 6B bf16 ≈12GB + KV/激活；24GB 卡留 4GB 余量；FP8 可选 |
| 稳定性 | 4h soak × N 客户端；随机断连/重连；token 校验；NaN/超时注入 |
| 观测 | 记录每步延迟、chunk 大小、动作统计、触发次数；不上传隐私图像 |
| 回退 | 模型/端口异常 → hold；连续失败 → 安全退出；不阻塞其他端口 |

**为什么服务也是创新点**：交互质量会被记录/展示；很多队会在多端口/长稳上翻车。把“恢复模式”与“服务门禁”一起做成可复现的工程资产，是差异化的一部分，但不是主押注。

### D.9 明确不做

- 不在运行时跑 SAM3/分割大模型/世界模型 MPC（单模型合规 + 延迟）。
- 不假设 depth/外参/force 存在；不依赖绝对 3D。
- 不复制全部 32 任务硬件；ORT 只做 14 个高价值任务。
- 不做“多模型投票/级联”；所有头共享一个 checkpoint。
- 不把公开榜占位分数当 baseline；不引用未核实的“29.7%”。

### E.3 Phoenix-BC 伪代码

```python
for epoch in range(E):
    for batch in mixture_loader(public, pars, undo, ort, neg):
        for ep in batch.episodes:
            parts = psg[ep.task]
            z = encode_intent(ep.language, parts)          # offline parse + 5 paraphrases
            for t in ep.timesteps:
                w = graph_weight(ep, t, parts) * retry_boost(ep, t)
                obs = mask_actions(ep.obs[t])              # only runtime keys
                a_hat = policy(obs, z, ep.state[t])
                L_bc = w * huber(a_hat, ep.action[t])

                L_pars = 0.0
                if t in ep.perturb_idx:
                    obs_p = ep.perturbed_obs[t]
                    L_pars = huber(policy(obs_p, z, ep.state[t]), ep.action[t])

                L_undo = 0.0
                if t in ep.undo_idx:
                    obs_u, a_u, z_u = ep.undo_sample(t)
                    L_undo = huber(policy(obs_u, z_u, ep.state[t]), a_u)

                L_ish = (
                    0.5 * ce(effect_head(obs), ep.effect[t]) +
                    0.5 * ce(state_head(obs), ep.state_label[t]) +
                    0.3 * bce(part_head(obs), ep.part[t]) +
                    0.2 * mse(value_head(obs), ep.value[t])
                )

                loss = L_bc + 0.5 * L_pars + 0.8 * L_undo + 0.5 * L_ish
                loss.backward()
        step()
```

**关键实现细节**：

- `mask_actions`：训练时保留全部 54-D + mask；送入 loss 时只对评测可用的维度算动作损失（左右臂/EE、gripper、pivot），其余维度只算辅助/忽略。否则模型会学到评测端收不到的动作。
- `undo_sample`：观测用 \(o_{t_p}\)，语言用“undo {part}”模板 + 原任务复述；动作目标是从 \(t_p\) 回到 \(t_g\) 的逆轨迹（位置/旋转取逆，夹爪按释放）。逆轨迹要在 ORT 上验证可达；不可达的 part 不做 undo 样本。
- `graph_weight`：用 PSG 的 DAG 最短路；`retry_boost` 只对 retry 段加 \(\beta\)，不要对整条轨迹加。
- 语言：每个 batch 随机抽 5 条复述之一；每 10 个 epoch 做一次“只留 1 条”的 held-out，防止过拟合。

### E.4 ISH 训练细节

- 标签不平衡：`undo`/`blocked` 稀少 → class weight 3–5；`on_track` 下采样。
- 时间平滑：状态标签在变化点附近 ±2 帧做 label smoothing，避免边界抖动。
- 检测阈值：在验证集上按“召回 ≥80%、误报 ≤1 次/30s”选 CUSUM 的 \(h\)；每任务单独校准。
- 修复选择：不在神经网络里学；用 PSG + 规则表，便于调试/合规。
- 辅助头不参与动作推理的梯度截断（`detach` 可选），避免意图损失干扰动作；先用联合训练，若动作掉点再 detach。

### E.5 训练数据构造伪代码

```python
def build_dataset(task):
    episodes = load_public(task)
    parts = psg[task]
    for ep in episodes:
        ep.part_state = infer_parts(ep, parts)       # rule + offline teacher
        ep.retry = mine_retry(ep, parts)             # part-constrained
        ep.perturb_idx = sample_perturb(ep, parts)
        ep.undo_idx = sample_undoable(ep, parts)
        ep.effect = label_effect(ep, parts)
        ep.state_label = label_state(ep, parts)
        ep.value = retry_value(ep, parts)
    return episodes
```

**人工抽检**：每任务 5–10 段，检查 part 边界/retry/undo；错误率 >10% 的任务退回重标。

## I. 创新点清单（按优先级）

> 每条含：动机 / 与现有方案的差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险。P0 = 本轮主押注；P1 = 支撑/门禁；P2 = 备选/后续。

### I.1 P0：Phoenix-BC（恢复感知行为克隆）

- **动机**：公开数据只有成功轨迹；官方人为干扰占 20% trial；BC 在“子目标被撤销/局部失败”状态上没有监督。
- **差异**：ReTVL 用 retry 价值重加权、GR-BC 用目标图重加权、ALIGN 用 advantage 条件、Kintsugi/EgoRecovery 用仿真/ego 视频；我们把 **retry mining + PARS 扰动 + 反事实撤销 + ORT 真实恢复 + 图重加权** 组合进同一个 BC 目标，不换底座、不加在线模型。
- **可行性**：WLA-1.0-Base 冻结 VLM、只训 DiT + projector，24GB 可跑；反事实样本离线合成；ORT 只补少量真实数据。
- **资源**：32 任务公开数据；1×24GB GPU（12–19 GPU-days）；2–3 天 part 标注；ORT 可选。
- **步骤**：PSG 标注 → retry mining → PARS → 反事实 undo → ORT 共训 → 混合比例扫 → 消融 A0–A7。
- **风险**：retry 标签噪声；逆轨迹不可达；恢复数据伤害 nominal。缓解：part 约束、ORT 验证、nominal guard、混合 <15%。

### I.2 P0：ISH（Intent-State Head，意图状态头）

- **动机**：策略不知道“人刚撤销了哪个子目标”，会继续原计划；需要可验证的状态/效果意图，而不是读心。
- **差异**：GUIDER/EgoRecovery 从 ego/gaze 推断人类意图；Intent-Informed MPC 用 gaze + DBN；我们只分类**可观测的干预效果**（undo/remove/relocate/block/none）和**策略状态**（on_track/local_error/subgoal_undone/goal_satisfied/unrecoverable/blocked），输出接修复状态机。
- **可行性**：标签来自 ORT 脚本 + PSG + 反事实；头很小；共享 backbone，单模型合规。
- **资源**：ORT 标签；1 GPU；1 人 2 周。
- **步骤**：定义标签 → 离线训练/混淆矩阵 → 阈值校准 → 状态机 → 在线配对评测。
- **风险**：误触发；类别不平衡；合规解释。缓解：保守阈值、连续确认、nominal guard、文档说明“辅助头非独立模型”。

### I.3 P0：ORT（Open Recovery Testbed，开源硬件恢复测试台）

- **动机**：没有公开的失败/恢复数据；仿真器不覆盖 UniBot 的接触/遮挡；需要物理 ground truth 验证 undo/relocate/block。
- **差异**：ABC 证明开源硬件 + 数据栈可行，但面向通用 BC；ORT 只做 **14 个恢复任务**（8 undo + 6 move/remove/block），脚本化干预 + 配对评测，不做 32 任务复制。
- **可行性**：SO-100/ARX 级双臂 + 3D 打印夹具 + 4 相机 + LeRobot 栈；2–3 周搭建；G1 可用时做子集验证。
- **资源**：约 $1–3k（SO-100 方案）或 G1 访问；1 人 2–3 周；14 任务耗材。
- **步骤**：BOM → 搭建/标定 → 脚本化干预 → 采 2–3 种恢复/任务 → 与公开数据混合 → 验证迁移。
- **风险**：embodiment gap；硬件延期；过拟合小测试台。缓解：混合 <15%、留出任务、SO-100 只做协议/可行性、G1 数据优先。

### I.4 P0：PSG（Part-State Graph，部件状态图）

- **动机**：需要 part 级进度来定义 retry/undo、重加权、修复选择；端到端 VLA 没有显式进度。
- **差异**：GR-BC 的 goal-reachability graph 假设子目标已知；我们为 32 任务建 **带 undoable 标志的 PSG**，同时用于训练重加权和运行时修复选择。
- **可行性**：3–8 parts/任务；规则 + 离线视觉教师；人工抽检。
- **资源**：1–2 人 2–3 天；无需新数据。
- **步骤**：schema → 标注 32 任务 → 抽检 → 建 DAG → 接入权重/修复表。
- **风险**：标注错误；任务变体。缓解：抽检 10%、错误率 >10% 重标、只对高置信 part 用 undo。

### I.5 P0：反事实撤销重标注

- **动机**：没有“子目标被撤销后怎么办”的演示；真机采 undo 昂贵。
- **差异**：Kintsugi 用仿真失败/恢复分支、EgoRecovery 用人类 ego 视频；我们从成功轨迹 **拼接 post-state 观测 + 逆动作**，零新硬件生成 undo/re-do 样本。
- **可行性**：对可逆 part 有效；逆轨迹用 pre-grasp 重放近似；ORT 验证。
- **资源**：PSG + replay；1 GPU；无需新数据。
- **步骤**：选 undoable part → 取 \(t_g,t_p\) → 拼观测 → 逆动作/重放 → 训练 → ORT 验证。
- **风险**：视觉跳变；逆动作不可达；标签错。缓解：只做可逆 part、加时间一致增强、ORT 可达性筛选。

### I.6 P0：动作桥接 + 有效性掩码

- **动机**：WLA 的 54-D 相对 EE 与官方 6-D 绝对 EE + 7-D pivot 不一致；直接截断会错。
- **差异**：显式 SE(3) 组合、工作空间限幅、速率限制、gripper 滞回、动作掩码、chunk 重叠平滑；把“数据集多 action 槽 vs 评测少槽”做成文档化适配层。
- **可行性**：纯工程；replay 可测。
- **资源**：1 工程师 1 周。
- **步骤**：映射表 → SE(3) 组合 → 限幅/平滑 → 单元测试 → 4h soak。
- **风险**：旋转/IK bug；范围不匹配。缓解：对拍官方 example、可视化、保守限幅。

### I.7 P1：恢复感知评测协议

- **动机**：nominal 成功率不能预测恢复成功率（RoboRecover）；需要单独测 recovery。
- **差异**：配对初始状态、开/关恢复、报告 recovery success / false trigger / detection latency；不只看总分。
- **可行性**：ORT + replay；统计简单。
- **资源**：ORT；eval harness；1 人 1 周。
- **步骤**：定义协议 → 配对种子 → 指标 → bootstrap/McNemar → 报告。
- **风险**：ORT 不具代表性。缓解：留出任务、公开数据 replay 交叉验证。

### I.8 P1：RPSM 2.0（稀疏 part-state 记忆）

- **动机**：长任务需要记住已完成/未完成子目标；全视频/世界模型太重。
- **差异**：只存 32×K 布尔 + effect 历史 + 预算，<1MB/端口；不跑图搜索/世界模型。
- **可行性**：简单工程；与 ISH 共用标签。
- **资源**：无额外。
- **步骤**：schema → 更新/衰减 → 接入动作条件 → 消融。
- **风险**：状态漂移；陈旧记忆。缓解：变化点强制更新、每 episode reset、置信度低时重扫。

### I.9 P1：部署门禁（Compliance / Endurance / Portfolio）

- **动机**：N 端口、180s、p99、交互质量都会影响成绩/可信度；服务崩了算法白搭。
- **差异**：把“恢复 watchdog + 每端口隔离 + 4h soak + 动作安全”做成可复现门禁，而不是赛后补丁。
- **可行性**：工程成熟。
- **资源**：1 工程师 2 周；N 客户端模拟。
- **步骤**：dispatcher → 微批 → watchdog → 断连/NaN 注入 → soak。
- **风险**：延迟/GPU 争用。缓解：FP8/降 chunk/队列上限。

### I.10 P1：SPA-lite（无 depth 的空间先验）

- **动机**：无 depth/外参，纯 2D 策略在精度任务（ZipUp/StorePaddle）不稳。
- **差异**：2D keypoint + 双目相对视差 + 腕部近景 + 离线标定先验；不跑在线 SAM3/3D centroid。
- **可行性**：中等；依赖双目纹理/标定。
- **资源**：离线教师；1 GPU；标注少量 keypoint。
- **步骤**：keypoint 标签 → 视差/深度头 → 视觉伺服 → 精度任务评测。
- **风险**：无纹理/遮挡；标定漂移。缓解：腕部近景主导、相对深度、失败回退。

### I.11 P2：Tactile-to-Vision（离线触觉教师）

- **动机**：接触-rich 任务缺力反馈；评测端无触觉。
- **差异**：OpenTac 级开源触觉只在**训练/ORT**用，蒸馏到视觉策略；评测不装传感器。
- **可行性**：研究级；需硬件与配对数据。
- **资源**：OpenTac/触觉夹爪；GPU；2–3 周。
- **步骤**：配对采集 → 触觉教师 → 视觉学生蒸馏 → 评测。
- **风险**：触觉-视觉 gap；时间。缓解：只做 2–3 个任务、P2。

### I.12 P2：GIC / 双目自标定

- **动机**：评测端不给相机参数；机器人在干预/碰撞后外参可能漂移。
- **差异**：用头部双目自标定相对外参 + 在线更新；不依赖绝对 depth。
- **可行性**：中等；纹理/算力受限。
- **资源**：标定数据；1 GPU。
- **步骤**：特征匹配 → 相对位姿 → 更新视差 → 精度评测。
- **风险**：无纹理/动态遮挡。缓解：离线先验 + 慢更新 + 失败回退。

4. **N 与控制频率**：N 具体值？控制频率？chunk 执行超时怎么办？
5. **动作范围**：EE/关节/夹爪/pivot 的数值范围、裁剪、单位；`ee` 的旋转表示（欧拉/轴角/四元数）？
6. **评分**：4.2 公式；超时/干预后的步骤分；人为干扰是否直接判失败？
7. **任务 ID/语言**：评测是否传 task id？语言是否只用 5 条复述之一？是否可能新复述？
8. **相机**：评测端头部双目是否已 rectify？腕部相机是否标定？图像是否 JPEG 压缩？
9. **base/waist**：是否允许移动 base/waist？安全限位？
10. **提交**：是否允许多次提交/排行榜更新频率？最终评审用哪次？

**如果只能问三个问题**：人为干扰协议、单模型/外部数据合规、N/控制频率。这三个直接决定架构是否成立。
