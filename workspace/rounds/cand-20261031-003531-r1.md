# 第 13 轮 · NEED-GEN：从「对准目标」到「对准需求」——用角色图泛化物体，用表情弱证据消解需求歧义

> 检索/复核日期：**2026-10-31（UTC）**。赛事身份不变：宇树 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1，32 项桌面任务，通才单模型赛道，选手自部署 + 官方远程真机 API。本轮是新灵感循环第 1 轮，研究线承接第 12 轮 CHUNK-SERVO。三个灵感词是「需求洞察」「物体泛化」「面部表情识别」。本轮不推倒 FACT-VLA、GEO-RESIDUAL、CHUNK-SERVO，而是在它们之上加一层「需求层」：**VLA 负责产生动作意图，伺服负责最后 3 厘米，NEED-GEN 负责回答「这 3 厘米到底要对准什么、什么才算完成」。**

## 0. 先给结论：最后 3 厘米之后，还有一个「最后 1 个谓词」

第 12 轮把「1 秒开环 chunk」改成了「30 步规划 + 5 步视觉伺服」，解决的是**什么时候修正**。但它默认了一件事：**修正的目标是对的**。真实失败里还有一类更隐蔽的错误——机器人把动作做得很漂亮，却对准了错误的对象、错误的部位、错误的完成标准。

三个例子：

- **HangCup**：夹爪确实靠近了杯架，但抓的是杯沿而不是杯柄；杯子挂上去 0.5 秒又掉了。伺服全程都在「对准」，只是对准了错误的 role。
- **PlugInEthernet**：插头接近了网口，但插的是旁边的另一个口；或者插入了 2 mm 就停了。动作 chunk 很平滑，谓词 `inserted(plug, port, depth≥d_min)` 从未为真。
- **人为干扰轴**：人手把目标挪走，机器人还在对旧位置做高精度伺服。它「看见」了变化，但不知道这个变化意味着自己的需求已经失效。

所以本轮的核心判断是：

> **通才模型的下一层瓶颈，不是动作精度，而是「需求洞察」：从语言、演示、场景几何和人类反馈里，恢复出评测真正检查的那组谓词，而不是只拟合演示的整段轨迹。**

第 12 轮已经有一个很强的证据：32 个任务的数据集合计有 **94 个评分步骤**，平均每任务约 **3 个**。这说明评测不是单一终局布尔，而是多阶段、多谓词的。**需求洞察就是把这 3 个左右的谓词从演示和语言里恢复出来，并用它来选择目标、判断完成、触发恢复。**

三个灵感词怎么落到方案里：

| 灵感词 | 最诱人的做法 | 在 UniBot 里的陷阱 | 本轮采用的合规版本 |
|---|---|---|---|
| **需求洞察** | 再训一个「任务成功预测器」或 reward model | 单模型规则；标注成本；评测分布未知 | **R-Need**：从 33k 成功演示 + 语言先验构建「角色-谓词」需求图；在线用贝叶斯滤波 + SPRT 做需求识别，不新增学习模型 |
| **物体泛化** | 训一个 6D 物体位姿/类别泛化网络 | 透明/反光/变形不可靠；第二个模型；未见物品没有 3D 标注 | **RRG**：把目标从「实例绝对位姿/目标图」改成「角色相对目标」；用 affordance/几何角色帧实例化到未见物体；腕部 color 相机已有内参 |
| **面部表情识别** | 接一个 FER 模型，读人类情绪 | 第二个模型；隐私；评测里人不一定在画面、也不一定有表情；野外 FER 本身只有 ~67% | **AFFEC**：只用同一 VLA checkpoint 的 VLM 做零样本表情/头部姿态提示；校准后作为**有上限的弱证据**；可离线、可关闭；绝不覆盖几何成功判据 |

一句话：**NEED-GEN = 需求图 + 角色相对目标 + 可校准的表情弱证据；VLA 仍是唯一学习策略，伺服仍是确定性控制器，表情只是一个可关闭的观测通道。**

## 1. 需求洞察：从「轨迹模仿」到「谓词恢复」

### 1.1 为什么语言不够，演示也不够

语言给出的是压缩指令（「把杯子挂到架子上」），它没有告诉你：

- 抓杯柄还是杯沿；
- 挂到哪一个钩子；
- 杯口朝哪边；
- 插入深度多少算成功；
- 先放稳再松手，还是松手后再调整。

演示给出的是**一条成功轨迹**，它包含上述信息，但被埋在高维视频里。行为克隆学的是 `p(a_t | o_t, l)`，它可能复现轨迹，却不一定显式恢复「哪一个谓词是必要的」。当初始位置、物体实例、背景变化时，轨迹分布偏移，模型就失去完成判据。

所以本轮把「需求」显式写成一个**角色-谓词图**：

```text
z = (b, φ, τ)
b: 物体 → 角色（target / receptacle / tool / support / distractor）
φ: 时序谓词公式（例如 F grasp_handle ∧ F handle_over_hook ∧ F stable）
τ: 每个谓词的容差（位置/角度/深度/时间）
```

以 HangCup 为例：

```text
roles: cup=target, hook=receptacle, table=support
predicates:
  P1: grasp_handle(cup)             # 夹爪中心在杯柄 frame 的容差内
  P2: handle_over_hook(cup, hook)   # 杯柄轴与钩口中心对齐
  P3: stable(cup, hook, 0.5s)       # 松手后 0.5s 内位姿漂移 < 2mm
φ = F P1 ∧ F P2 ∧ F P3,  P1 ≺ P2 ≺ P3
τ = (5mm, 5°, 2mm/0.5s)
```

以 PlugInEthernet 为例：

```text
roles: plug=tool, port=receptacle, cable=support
predicates:
  P1: grasp_plug(plug)
  P2: align_axis(plug, port)        # 轴向夹角 < 3°
  P3: inserted(plug, port, depth)   # 插入深度 > d_min，且回退 < 1mm
  P4: stable_connection(plug, port, 0.5s)
φ = F P1 ∧ F P2 ∧ F P3 ∧ F P4,  P1 ≺ P2 ≺ P3 ≺ P4
```

### 1.2 需求不是唯一确定的：歧义是常态

同一个语言指令可能对应多个合法需求。例如「把杯子挂好」可以是「杯柄挂钩」也可以是「杯沿挂架」；「把药倒出来」可以是「倒到瓶盖里」也可以是「倒到桌上」。这些需求在几何上可能直到某个阶段才可区分。

因此本轮不假设「需求已知」，而是维护一个**需求后验**：

```math
w_k(t) = p(z_t = z_k \mid l, D, S_{1:t}, a_{1:t})
```

其中 `l` 是语言，`D` 是演示库，`S_{1:t}` 是场景历史，`a_{1:t}` 是人类表情/头部姿态证据（可选）。

在线更新用一个带转移的隐马尔可夫滤波：

```math
\log w_k(t) = \log \sum_i w_i(t-1) T_{ik}
             + \log p(y_t \mid z_k)
             + \mathbb 1[h_t=1] \log p(a_t \mid z_k)
             + \text{const}
```

- `T_{ik}` 允许「人把任务改了」：小概率从需求 `i` 跳到 `k`；
- `y_t` 是谓词观测（真/假/未知，带敏感度/特异度）；
- `a_t` 是表情证据，只在人可见时使用；
- 候选集 `Z_t` 从演示库检索 top-K，K 很小（≤8，含角色绑定后 ≤16）。

### 1.3 什么时候该「问」，什么时候该「做」

需求后验有两种用途：

1. ** exploit**：如果 `w_max ≥ 1-δ`，直接按 MAP 需求选目标、执行、判断完成。
2. **probe**：如果熵高、top-2 差距小，不要瞎猜；选择一个**安全的信息增益动作**，让场景自己暴露需求。例如：
   - 把杯子稍微抬起/旋转，让杯柄和杯沿在腕部相机里分开；
   - 把插头退后半厘米，换一个角度看网口；
   - 如果人在画面里，短暂停一下并看向人，用表情/点头作为弱证据。

信息增益用一步 lookahead 近似：

```math
IG(g) = H(w_t) - \mathbb E_{y'\mid g}\left[H(w_{t+1})\right]
```

只在安全动作集 `G_safe` 里最大化 `IG`；如果没有安全 probe，就退回 VLA 开环并**不宣布完成**。这条「歧义时不安慰自己」的规则，是本轮安全性论证的核心。

## 2. 物体泛化：从「实例目标图」到「角色相对目标」

### 2.1 第 12 轮 DG-KEYFRAME 的隐含假设

第 12 轮从 33k 成功演示里检索「目标-夹爪相对位姿 + 腕部目标图」。这在**见过的物体实例**上很强，但在「未见物品」轴上有一个隐含假设：

> 测试物体的外观/几何与演示中的实例足够相似，检索到的目标图/相对位姿可以直接迁移。

一旦物体换形状（不同杯柄、不同插头、不同瓶子），目标图匹配会失败；绝对相对位姿也会因为物体尺寸/抓取点变化而偏。第 12 轮用「相对目标」抗位置泛化，但没有完全解决**物体实例泛化**。

### 2.2 角色相对目标

本轮把目标定义在**角色帧**上，而不是物体实例上：

```text
T_role(t) = 物体在当前场景中的角色帧（手柄轴、杯口平面、插槽轴、钩口平面）
g_template = 从演示学到的「角色 → 夹爪」相对目标
T_goal(t) = T_role(t) · g_template
```

角色帧的例子：

| 角色 | 角色帧定义 | 估计方式 |
|---|---|---|
| `handle` | 原点在柄中心，z 沿柄轴 | 几何基元（圆柱/闭合曲线）+ VLM 零样本热图 |
| `rim` | 原点在杯口中心，z 沿杯口法向 | 椭圆/平面拟合 + 双目深度 |
| `slot` | 原点在插槽中心，z 沿插入轴 | 矩形/线段检测 + 局部点云 PCA |
| `hook` | 原点在钩口中心，z 沿钩口法向 | 圆弧/平面拟合 |
| `container` | 原点在容器质心，z 沿开口方向 | 点云凸包/平面 + 开口检测 |

关键点：**目标不再依赖「这是哪一个杯子」，而依赖「这个杯子的手柄帧在哪里」。** 未见物体只要角色帧可估计、局部几何在容差内，就可以复用同一个 `g_template`。

这和第 12 轮的 `T_target_ee*` 是同一数学形式，但语义从「目标物 → 夹爪」推进到「角色帧 → 夹爪」。前者绑定实例，后者绑定功能。

### 2.3 角色绑定是新的单点故障

角色相对目标有一个致命前提：**角色绑定必须对**。如果把杯沿当成杯柄，角色帧估计得再准也没用。因此本轮把角色绑定也纳入需求后验：

```text
候选需求 = 角色绑定候选 B × 谓词图模板 Φ
```

角色绑定用带约束的匈牙利分配：

```text
score(i, r) = w1·affordance_score(o_i, r)
            + w2·geometry_score(o_i, r)
            + w3·language_score(r, l)
```

保留 top-m 个绑定（m≤4），而不是只取一个。如果绑定 margin 低，需求后验自然会更分散，触发 probe 或回退，而不是自信地错下去。

### 2.4 一个可检验的泛化条件

定义**角色等价**：两个物体 `o, o'` 对角色 `r` 等价，如果它们的角色帧估计在容差内，且局部几何/affordance 描述子在模板支持域内。若角色绑定正确、角色帧误差 `≤ ε_r`、模板误差 `≤ ε_g`，则实例化目标误差满足

```math
\|\log(T_{\text{goal}}^{-1} T_{\text{goal}}^*)\|
\le \varepsilon_r + \varepsilon_g + O(\varepsilon_r\varepsilon_g)
```

这是 SE(3) 上的三角不等式 + BCH 展开。它不证明「任意未见物体都能泛化」，但给出了一个可测的条件：**角色帧误差和绑定错误率**。本轮用留一物体（leave-one-object-out）实验直接测这两个量。

## 3. 面部表情识别：从「情绪识别」到「需求满足的弱证据」

### 3.1 先说最危险的联想

最诱人的做法是：接一个 FER 模型，读人的表情，开心就继续，皱眉就停。这个做法在 UniBot 里有四个问题：

1. **单模型规则**：FER 模型是第二个学习模型，风险高。
2. **可用性**：评测时人不一定在画面里；人的表情不一定针对机器人；口罩/侧脸/遮挡都会失效。
3. **可靠性**：专用 FER 模型在 AffectNet-7 上约 67%，通用 VLM 零样本不会更好，三分类正/中/负也不稳；跨文化、跨人有严重偏差。
4. **隐私/伦理**：把评测者当成情绪信号源，容易越界。

所以本轮**不把 FER 当控制器**，也不把它当核心收益来源。它只做一个东西：**对「当前需求是否正在被满足」提供一条有上限的弱证据**。

### 3.2 合规的用法：同一 checkpoint + 校准 + 上限 + 可关闭

三种合规模式，按风险从低到高：

| 模式 | 做法 | 何时用 |
|---|---|---|
| **C1 离线** | 只用 FER 离线给演示打「人类满意/不满意」弱标签，帮助构建需求图；线上不跑 FER | 默认；最安全 |
| **C2 确定性** | 线上只用几何/语言/演示；表情完全不参与 | 评测人不稳定时 |
| **C3 同 checkpoint** | 用 VLA 自带的 VLM，文本提示「positive / neutral / negative」，取 logits；不加载第二套权重 | 单任务通道/人机协作场景；需官方解释 |

C3 的具体约束：

- 只在人可见、任务处于「需求歧义」或「接触」阶段时查询；
- 查询频率 ≤2 Hz，异步，不阻塞 5 步伺服；
- 输出三类概率，先用温度缩放/混淆矩阵校准；
- 对数似然比上限 `|log LR| ≤ log 3`，单帧不能翻盘；
- 校准门不过（三分类 balanced accuracy <0.65 或 ECE >0.10）就自动关闭，退回 C1/C2；
- 不存人脸图、不做身份识别、不做情绪画像；会话结束即删；
- **表情永远不能替代几何谓词**：它可以触发「再确认」，不能触发「宣布成功」。

### 3.3 表情到底能帮什么

在需求歧义场景里，表情是一个**弱先验**：

```math
p(a_t \mid z_k) = \sum_{s\in\{0,1\}} p(a_t \mid s)\, p(s \mid z_k, h_t)
```

- `s=1` 表示「当前需求正在被满足/进展符合预期」；
- `s=0` 表示「当前需求不对/没有进展」；
- `p(a_t|s)` 来自校准后的混淆矩阵；
- `p(s|z_k,h_t)` 来自候选需求的进度模型；
- 只有 `h_t=1`（人可见）时才更新。

它最适合的场景不是「读心」，而是**消解两个几何上几乎一样的需求**：比如杯柄挂 vs 杯沿挂、插这个口 vs 插旁边那个口、倒进瓶盖 vs 倒到桌上。在这些场景里，几何证据可能直到很晚才分化，而人的一个皱眉/点头可以提前几秒提供方向。

### 3.4 一个受控合成实验：收益和风险都很大

我做一个最小的合成实验，把「表情弱证据」的机制单独隔离出来：

- 两个候选需求在几何上**完全相同**，只有人类满意度能区分；
- 真实需求满足度随时间上升；错误孪生需求的预测满足度只有 0.2 倍；
- 每帧以概率 `ρ` 有人在场并给出表情；表情由校准模型生成；
- 比较：无表情、校准表情、失校准表情、反相关表情；
- T=24，N=30,000，随机猜测准确率 0.5。

结果（详细设置见产物区 §6.1）：

| 人在场率 ρ | 无表情 | 校准表情 | 失校准表情 | 反相关表情 |
|---:|---:|---:|---:|---:|
| 0.2 | 0.500 | **0.589** | 0.586 | 0.405 |
| 0.6 | 0.500 | **0.767** | 0.748 | 0.215 |
| 1.0 | 0.500 | **0.942** | 0.914 | 0.028 |

读法：

- 校准表情在歧义场景里能把需求识别从 0.50 提到 0.77（ρ=0.6）甚至 0.94（ρ=1.0）；
- 失校准仍可能「碰巧有用」，但收益被侵蚀；
- **反相关通道会把准确率压到机会水平以下**——这正是不应该把 FER 当控制器的原因。

第二个合成实验测角色相对目标：物体位姿偏移 5cm/10°，角色帧估计噪声 3mm/2°，N=50,000。结果是实例绝对目标平均误差 **62.8 mm / 7.97°**，角色相对目标 **3.8 mm / 1.60°**；但如果角色绑定有 2% 错误，平均误差升到 8.8 mm，5% 错误升到 16.9 mm。**物体泛化的收益很大，但对绑定错误极其敏感。**

## 4. 把三者接起来：NEED-GEN 的一轮执行

```text
reset():
  w ← prior(l, D);  B ← ∅;  plan ← ∅;  ẑ ← None

get_action(obs):
  1. S_t ← scene_graph(obs)                  # 物体、位姿、affordance
  2. B_t ← role_binding(S_t, l)              # top-m 匈牙利绑定
  3. Z_t ← candidate_needs(B_t, l, D)        # B × Φ，剪枝到 K
  4. w_t ← HMM_update(w_{t-1}, Z_t, y_t, a_t)
  5. if ambiguous(w_t):
        if human_visible and affect_enabled:
            a_t ← async_query_affect(obs)     # 同一 VLM，校准，限幅
            w_t ← update(w_t, a_t)
        if still ambiguous:
            g_probe ← argmax IG(g) over G_safe
            return servo_chunk(g_probe, plan=None)
  6. ẑ ← MAP(w_t) or committed need
  7. plan ← async_vla(obs, l, need_hint=ẑ)   # 不阻塞；过期用旧 plan + 伺服
  8. g* ← select_goal(ẑ, S_t, w_t)           # 角色相对；歧义时 maximin/probe
  9. a_ff ← plan[plan_idx : plan_idx+H_c]    # H_c=5
     Δ ← servo(obs, g*)                      # clip(K_p e + K_d ė)
     a_cmd ← compose(a_ff, Δ)
 10. if need_violation or edit_detected:
        RECOVER: hold → re-localize → update w with transition → replan
 11. if φ_ẑ(S_t) true with margin and committed:
        declare success; stop
 12. return adapter.to_api(a_cmd)
```

它和第 12 轮 CHUNK-SERVO 的关系：

- **保留**：30 步 VLA 规划、5 步伺服、GEO-RESIDUAL 编辑检测、官方 WLA adapter。
- **升级**：目标从「检索到的实例相对位姿」升级为「角色帧实例化的需求谓词目标」；完成判据从「VLA plan 用完/视觉误差小」升级为「需求图谓词满足 + 后验已 commit」。

- **不变**：VLA 是唯一学习模型；伺服无学习权重；不逐任务训策略。

- 需求图相对「语言先验 + 固定模板」没有 +10pp：砍掉需求图，只保留角色相对目标。

- 表情对需求识别或干预检测没有可测增益：关闭 AFFEC，只在论文/报告里保留离线分析。
- 真机 A/B 不到 3/5 任务 +10pp：不烧正式 320 trials。

## 7. 一句话最大的风险

**当前方案最大的风险是：面部表情在真实评测里既可能不可见、也可能与任务需求无关；若把需求洞察的收益押在 FER 上，方案会退化成昂贵的基线，因此 FER 必须是可校准、可关闭的弱证据，核心收益必须由「语言 + 演示 + 角色几何」承担。**

## 2. 问题形式化

### 2.1 场景图

在时刻 `t`，观测为

```math
o_t = (I_t^{LH}, I_t^{RH}, I_t^{LW}, I_t^{RW}, q_t, e_t, l)
```

其中 `I` 是四路 RGB，`q_t` 是本体状态，`e_t` 是 EE 位姿，`l` 是语言。场景图定义为

```math
S_t = (O_t, T_t, A_t, R_t),
```

- `O_t = {o_1,...,o_n}`：物体槽位（n≤20）；
- `T_t = {T_i ∈ SE(3)}`：物体在 base 系的位姿；
- `A_t = {a_i}`：affordance 描述子（局部几何 + VLM 零样本语义）；
- `R_t`：物体间空间关系。

### 2.2 角色与角色绑定

定义角色集合

```math
\mathcal R = \{\text{target}, \text{receptacle}, \text{tool}, \text{support}, \text{distractor}, \text{human}\}.
```

角色绑定是一个带元数约束的部分单射

```math
b: O_t \rightharpoonup \mathcal R,
```

例如一个任务可以要求 `target=cup`、`receptacle=hook`、`support=table`，其余物体为 `distractor`。实际实现保留 top-m 个绑定 `B_t = {b_1,...,b_m}`（m≤4），而不是只取一个。

对物体 `o_i` 和角色 `r`，角色帧定义为

```math
T_{i,r} = h_r(o_i, S_t) \in SE(3),
```

并带不确定度 `Σ_{i,r}`。角色帧的例子：

| 角色 | 帧定义 | 估计方式 |
|---|---|---|
| `handle` | 原点在柄中心，z 沿柄轴 | 圆柱/闭合曲线拟合 + VLM affordance 热图 |
| `rim` | 原点在杯口中心，z 沿杯口法向 | 椭圆/平面拟合 + 双目深度 |
| `slot` | 原点在插槽中心，z 沿插入轴 | 矩形/线段检测 + 局部点云 PCA |
| `hook` | 原点在钩口中心，z 沿钩口法向 | 圆弧/平面拟合 |
| `container` | 原点在容器质心，z 沿开口方向 | 点云凸包/平面 + 开口检测 |

### 2.3 谓词与需求图

一个谓词定义为

```math
P = (\text{type}, \text{args}, \tau),
```

其中 `type` 是谓词类型，`args` 是物体/角色参数，`τ` 是容差。谓词带一个连续 margin `m_P(S_t,b) ∈ R`，真值为

```math
P(S_t,b) = \mathbb 1[m_P(S_t,b) \ge \tau_P].
```

例子：

| 谓词 | margin 例子 | 容差例子 |
|---|---|---|
| `grasp_handle(cup)` | 夹爪中心到柄帧原点的距离 / 夹角 | 5 mm / 5° |
| `handle_over_hook(cup, hook)` | 柄轴与钩口中心的最小距离 / 轴夹角 | 5 mm / 5° |
| `inserted(plug, port)` | 插入深度 `d` 与轴夹角 `θ` | `d ≥ d_min`；`θ ≤ 3°` |
| `stacked(cup_i, cup_j)` | 杯口中心 xy 偏差 / 平面夹角 | 4 mm / 4° |
| `stable(obj, 0.5s)` | 0.5 s 内位姿漂移 | 2 mm / 3° |
| `contained(obj, container)` | 物体质心是否在容器内 | 0（布尔） |

一个**需求图**是一个三元组

```math
z = (b, \varphi, \tau),
```

其中 `φ` 是定义在谓词上的有界时序公式。本报告限制为「有界最终合取 + 先后约束」：

```math
\varphi = \bigwedge_{j=1}^{m} \mathbf F P_j,
\qquad
P_i \prec P_j \text{ for some pairs},
```

并可加安全约束 `\mathbf G \neg P_{\text{fail}}`。这足够表达 32 个桌面任务的主要结构，同时保持推理 tractable。

**真实需求 `z*`** 是评测器实际检查的成功谓词；机器人不直接观测 `z*`，只观测语言、演示、场景和（可选）人类表情。

### 2.4 候选需求集

离线需求库按 `(task, phase)` 分片。运行时先由语言/任务检索候选谓词图模板 `Φ_t`，再与角色绑定候选 `B_t` 做笛卡尔积：

```math
Z_t = \{ (b, \varphi, \tau) : b \in B_t,\ \varphi \in \Phi_t \}.
```

剪枝到 `K ≤ 16`。先验由检索分数给出：

```math
p(z_k \mid l, D) = \frac{\exp(\kappa s_k)}{\sum_{j} \exp(\kappa s_j)},
```

其中 `s_k` 是语言/任务/相位的检索分数（ANN 索引 + 规则过滤）。

### 2.5 需求后验与隐马尔可夫滤波

令

```math
w_k(t) = p(z_t = z_k \mid l, D, S_{1:t}, a_{1:t}).
```

允许需求在人为干扰后改变，用转移矩阵

```math
T_{ik} = p(z_t = z_k \mid z_{t-1} = z_i)
      = \begin{cases}
        1-\epsilon, & i=k,\\
        \epsilon/(K-1), & i\ne k,
        \end{cases}
```

其中 `ε` 很小（例如 0.01）。后验更新：

```math
\log w_k(t) =
\log \sum_i w_i(t-1) T_{ik}
+ \log p(y_t \mid z_k)
+ \mathbb 1[h_t=1] \log p(a_t \mid z_k)
+ \text{const}.
```

#### 2.5.1 谓词观测模型

每个谓词检测器返回 `y_{P,t} ∈ {0,1,⊥}`（真/假/未知），并带敏感度 `α_P` 和特异度 `β_P`：

```math
p(y=1 \mid P=1)=\alpha_P,\quad
p(y=0 \mid P=1)=1-\alpha_P,
```
```math
p(y=0 \mid P=0)=\beta_P,\quad
p(y=1 \mid P=0)=1-\beta_P,
```

`y=⊥` 时似然为 1。对候选 `z_k`，用当前 VLA 计划/相位预测谓词状态 `π_k(P) ∈ {0,1}`：有 plan 时把 plan 的 EE 轨迹前向检查谓词；没有 plan 时用相位先验。则

```math
p(y_t \mid z_k) = \prod_{P \in \varphi_k}
p(y_{P,t} \mid \pi_k(P)) \cdot \epsilon_{\text{obs}},
```

`ε_obs` 是小的观测下限，避免单个零似然把候选永久排除。未知谓词贡献 1。

#### 2.5.2 表情证据模型

令 `a_t ∈ {positive, neutral, negative, absent}`，`h_t ∈ {0,1}` 表示人是否可见。校准后的三类混淆矩阵为

```math
C_{a,s} = p(a_t = a \mid s_t = s), \quad s \in \{0,1\},
```

其中 `s=1` 表示「当前需求正在被满足/进展符合预期」，`s=0` 表示「需求不对/没有进展」。候选 `z_k` 的进度模型给出 `p(s \mid z_k, h_t)`；实现上可用下一个必需谓词的归一化 margin 过 logistic，或用演示统计的相位表。于是

```math
p(a_t \mid z_k) = \sum_{s\in\{0,1\}} C_{a_t,s}\, p(s \mid z_k, h_t).
```

为防止单帧翻盘，对数似然比限幅：

```math
\left|\log \frac{p(a_t \mid s=1)}{p(a_t \mid s=0)}\right| \le \log 3.
```

校准门不过时，直接把该通道权重设为 0，退回 C1/C2。

### 2.6 角色相对目标

从演示库为每个 `(task, phase, role)` 学习一个角色相对目标模板

```math
g_{\text{template}} \in SE(3),
```

在线实例化：

```math
T_{\text{goal}}(t) = T_{\text{role}}(t)\, g_{\text{template}}.
```

对候选需求 `z_k`，目标集合为

```math
G(z_k) = \{ T_{\text{role}}(t)\, g_{k,j} : P_j \text{ 是 } z_k \text{ 的下一个未满足谓词} \}.
```

目标误差用左不变度量 `d(·,·)` 度量。若角色帧误差 `d(T_{\text{role}}, T_{\text{role}}^*) ≤ ε_r`，模板误差 `d(g, g^*) ≤ ε_g`，则

```math
d(T_{\text{goal}}, T_{\text{goal}}^*)
\le d(T_{\text{role}} g, T_{\text{role}}^* g) + d(T_{\text{role}}^* g, T_{\text{role}}^* g^*)
= ε_r + ε_g,
```

因为左不变度量满足 `d(A g, B g) = d(A,B)`。如果角色绑定错误，`T_{\text{role}}` 对应的是另一个物体，上述界不成立；误差可以任意大。这是角色绑定必须进入需求后验的原因。

### 2.7 可辨识性条件

视觉/需求推断只在以下条件同时满足时启用：

1. 目标/受器在头部双目或腕部视野内；
2. 角色帧估计协方差低于阈值（例如平移 ≤5mm、旋转 ≤3°）；
3. 谓词检测器的敏感度/特异度高于阈值；
4. 真实需求在候选集 `Z_t` 中（由检索/人工模板保证）；
5. 任务属于刚体接触类（A 档）；
6. 表情通道额外要求：人可见、校准门通过、隐私许可。

任一条不满足 → 回退 VLA 开环或 CHUNK-SERVO 的实例相对目标；不硬做需求推断，也不宣布完成。

## 3. 算法设计

### 3.1 总体架构

```text
                    ┌─────────────────────────────────────┐
                    │  Evaluator (N ports 8765..8765+N-1) │
                    └──────────────┬──────────────────────┘
                                   │ websocket: obs / action chunk
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Per-port NEED-GEN PolicyService    │
                    │  ├─ scene graph / role binding      │
                    │  ├─ need library + HMM filter       │
                    │  ├─ role-relative goal selector     │
                    │  ├─ visual servo (IBVS/PBVS)        │
                    │  ├─ plan cache (30-step VLA plan)   │
                    │  ├─ affect query (optional, async)  │
                    │  └─ action adapter (WLA 54D → API)  │
                    └──────────────┬──────────────────────┘
                                   │ async, batched
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Shared VLA server (GPU)            │
                    │  UnifoLM-WLA-1.0, 30-step chunk     │
                    └─────────────────────────────────────┘
```

- 每个端口一个 `NeedGenPolicy` 实例，独立 `reset()`、独立需求后验、独立 plan cache、独立绑定状态。
- 需求图/角色绑定/伺服是 CPU 线程；VLA 请求异步、可批处理；表情查询低频率、异步。
- 共享 VLA server 用 session ID 区分端口；模型权重只有一份，不违反单模型。

### 3.2 离线：需求库与角色目标库

```python
def build_library(task, episodes, vlm):
    library = NeedLibrary(task)
    for ep in episodes:
        phases = segment_phases(ep)            # FACT-VLA CPT / 人工/半自动
        for ph in phases:
            b = annotate_binding(ep, ph)       # 物体 → 角色
            predicates = annotate_predicates(ep, ph, b)
            for P in predicates:
                margin = compute_margin(ep, ph, b, P)
                tolerance = quantile(margin over successful demos, 0.95)
            phi = induce_precedence(predicates)
            g = extract_relative_goal(ep, ph, b)   # 角色帧 → 夹爪
            library.add(b, phi, tolerances, g)
    library.cluster_and_prune(K=8)
    library.build_ann_index()
    return library
```

要点：

- **相位分割**：优先用 FACT-VLA 的相位化 BC；没有标签时用「夹爪闭合/接触/目标进入腕部视野」启发式。
- **容差学习**：用成功演示的 margin 分布的上分位数（例如 95%），而不是拍脑袋常数；再用单任务通道校准。
- **角色帧标注**：对刚体任务用几何基元；对透明/反光物体，若角色帧不可靠，不建精确模板，只建图像/相位模板。
- **表情弱标签（可选）**：用 FER 离线给演示打「人满意/不满意」标签，辅助选择关键帧；不进入在线模型。

### 3.3 在线主循环

```python
class NeedGenPolicy:
    def reset(self, language, task_id):
        self.l = language
        self.task = task_id
        self.w = self.library.prior(language, task_id)
        self.binding = None
        self.plan = None
        self.plan_idx = 0
        self.committed = None
        self.phase = "INIT"
        self.t = 0
        self.affect = None

    def get_action(self, obs):
        self.t += 1
        S = self.scene_graph(obs)
        B = self.role_binding(S, self.l)          # top-m
        Z = self.candidate_needs(B, self.l)       # B × Φ, K ≤ 16
        self.w = self.hmm_update(self.w, Z, S)    # 谓词观测

        if self.ambiguous(self.w):
            if self.affect_enabled and self.human_visible(obs):
                a = self.query_affect_async(obs)  # 同一 VLM，限幅
                if a is not None:
                    self.w = self.hmm_update(self.w, Z, S, affect=a)
            if self.ambiguous(self.w):
                g_probe = self.choose_probe(Z, S) # max IG over G_safe
                return self.servo_chunk(g_probe, plan=None)

        z = self.commit_or_map(self.w)
        if self.need_plan(obs):
            self.plan = self.request_vla_async(obs, z)
        if self.plan is None:
            return self.safe_hold()

        g = self.select_goal(z, S, self.w)        # 角色相对；歧义时 maximin
        a_ff = self.plan[self.plan_idx:self.plan_idx + self.H]
        delta = self.servo(obs, g)                # clip(K_p e + K_d ė)
        a_cmd = compose_relative(a_ff, delta)

        self.plan_idx += self.H
        if self.plan_idx >= len(self.plan):
            self.plan = None

        if self.violation(S, z):
            self.enter_recover(S)
        if self.success(S, z) and self.committed:
            self.done = True
        return self.adapter.to_api(a_cmd, obs, self.token)
```

异常处理：

- 冷启动 VLA 同步超时 → 安全 hold；不返回 NaN/错误形状。
- 伺服失败 → 返回上一组合法 chunk 或 hold。
- 表情查询超时/低置信 → 跳过，不阻塞。
- `reset()` 清理所有状态；不同端口不共享可变状态。

### 3.4 角色绑定

```python
def role_binding(S, l):
    scores = {}
    for o in S.objects:
        for r in ROLES:
            scores[o, r] = (
                1.0 * affordance_score(o, r, l) +
                0.8 * geometry_score(o, r) +
                0.5 * language_score(r, l)
            )
    assignments = hungarian_with_arity(scores, arity=ROLE_ARITY)
    return top_m(assignments, m=4, margin=0.15)
```

- `affordance_score`：同一 VLM 的零样本提示（"handle", "rim", "slot", "hook"）返回区域/热图分数，或几何基元检测器的置信度。
- `geometry_score`：尺寸/形状/开口方向与角色的兼容性。
- `language_score`：物体名词与角色描述的匹配。
- 匈牙利分配 `O(n^3)`，n≤20；场景不变时缓存。
- 绑定 margin 低 → 需求后验更分散 → 触发 probe/回退。

### 3.5 需求滤波、commit 与 probe

#### 3.5.1 滤波

```python
def hmm_update(w, Z, S, affect=None):
    w_pred = w @ transition_matrix        # K×K
    for k, z in enumerate(Z):
        loglik = predicate_loglik(S, z)
        if affect is not None and z.binding == binding_of(affect):
            loglik += capped_affect_loglik(affect, z)
        w_pred[k] *= exp(loglik)
    return normalize(w_pred)
```

#### 3.5.2 commit / ambiguity

- `w_max = max_k w_k`，`H_n = H(w)/log K`。
- **commit**：`w_max ≥ 1-δ` 且 `H_n ≤ θ_H` 连续 `N_c` 帧。
- **ambiguous**：`H_n ≥ θ_H` 或 `w_max - w_2 ≤ θ_m` 连续 `N_a` 帧。
- **switch**：执行失败/编辑检测后，若 `w_2 - w_max ≥ θ_s` 连续 `N_s` 帧，切换需求。
- 默认 `δ=0.2, θ_H=0.5, θ_m=0.15, N_c=3, N_a=2, N_s=2`；在单任务通道调。

SPRT 版本（可选，用于「执行失败还是需求错误」）：

```math
\Lambda_t = \log \frac{p(y_{1:t} \mid z_{\text{best}})}
{p(y_{1:t} \mid z_{\text{alt}})},
```

若 `Λ_t < -B` 切到 `z_alt`；若 `Λ_t > A` 继续 commit。`A,B` 由目标误判率/漏判率决定。这个版本比固定阈值更有原则，但需要可靠的谓词似然。

#### 3.5.3 probe

```python
def choose_probe(Z, S):
    best_g, best_ig = None, -inf
    for g in safe_probes(S):
        ig = expected_information_gain(self.w, Z, S, g)
        if ig > best_ig:
            best_g, best_ig = g, ig
    return best_g if best_ig > IG_MIN else None
```

安全 probe 例子：

- 把物体抬高 2–3 cm，让被遮挡的柄/口/槽进入视野；
- 把物体旋转 ±15°，让两个几何假设分开；
- 后退 3 cm，换一个视角；
- 人可见时，短暂停 + 转头看向人（social probe），用表情/点头作为弱证据。

如果没有安全 probe，回退 VLA 开环，**不宣布完成**。

### 3.6 目标选择与伺服

#### 3.6.1 目标选择

对每个候选 `z_k`，生成目标集 `G(z_k)`。效用：

```math
U(g, z_k) = -\left(e_p^\top \Sigma_p^{-1} e_p + e_r^\top \Sigma_r^{-1} e_r\right)
- \lambda_c\, c(g) - \lambda_r\, r(g),
```

其中 `e = log(T_{\text{ee}}^{-1} T_{\text{goal}})`，`c(g)` 是时间/移动成本，`r(g)` 是碰撞/超限风险。

- **已 commit**：`g^* = \arg\max_{g \in G(\hat z)} U(g, \hat z)`。
- **歧义**：`g^* = \arg\max_{g \in G_{\text{safe}}} \min_k U(g, z_k)`（maximin），或 `g_probe = \arg\max IG(g)`。
- **不要平均不兼容的目标**：两个需求的目标可能相差 10 cm，平均会撞到中间物体。歧义时要么 probe，要么 maximin，要么 hold。

#### 3.6.2 伺服

沿用 CHUNK-SERVO：

```math
e(t) = \log\left(T_{\text{ee}}(t)^{-1} T_{\text{goal}}(t)\right),
```
```math
\Delta = \mathrm{clip}\left(K_p e + K_d \dot e,\ \pm\delta_p,\ \pm\delta_r\right),
```
```math
a_{\text{cmd}} = a_{\text{ff}} \circ \exp(\Delta).
```

- `δ_p` 每块最多 1 cm，`δ_r` 最多 0.05 rad；避免伺服压过 VLA 的语义意图。
- 接触段：法向增益乘 0.3–0.5 并低通；切向保留；`r_grasp` 突变 → 滑移处理。
- 延迟补偿：`K_eff = K_0/(1+\tau/\tau_0)`；`τ_0=50ms`；Smith 预测/卡尔曼预测。
- 若 `||Δ||` 连续 3 块 > 阈值，判定角色帧/标定异常，回退 VLA 或重定位。

### 3.7 终止、恢复与状态机

```text
INIT ──first obs──▶ INFER ──committed──▶ SERVO
  ▲                    │                  │
  │                    ├─ ambiguous ──▶ PROBE
  │                    │                  │
  │                    │                  ├─ d_t < d_c ──▶ CONTACT
  │                    │                  │                 │
  │                    │                  │                 └─ released ──▶ SERVO
  │                    │                  │
  │                    └── violation ◀────┴── RECOVER ◀── edit_score > θ_e
  │                                              │
  └──────────────────────────────────────────────┘
任意状态 ──success + committed──▶ DONE
```

- **INFER**：需求后验未 commit；不执行高风险动作；可 probe。
- **SERVO**：PBVS 主导，IBVS 辅助。
- **CONTACT**：`d_t < d_c` 或相位=接触；法向缩幅、切向保留；滑移检测。
- **PROBE**：安全信息增益动作；不宣布完成。
- **RECOVER**：编辑检测/需求违反；先停，再重定位；目标可见 → 更新绑定/需求；不可见 → VLA 重规划。
- **DONE**：`φ_ẑ` 满足且 commit；清理状态，等待 `reset()`。

#### 3.7.1 终止条件

```math
\text{terminate} \iff
\left(\bigwedge_{P \in \varphi_{\hat z}} P(S_t, \hat b)\right)
\land \left(w_{\max} \ge 1-\delta\right)
\land \left(H_n \le \theta_H\right).
```

- 只满足谓词但后验未 commit → 不终止；继续验证/probe。
- 后验 commit 但谓词不满足 → 不终止；继续执行/恢复。
- 表情 negative 但几何成功 → 请求再确认，不覆盖几何成功。
- 表情 positive 但几何未成功 → 不终止；表情不能替代谓词。

#### 3.7.2 需求违反与恢复

- 若 `z_hat` 的某个必需谓词在 `N_fail` 次尝试后仍为假，或 VLA plan 耗尽，提升 violation score。
- 若 `edit_score > θ_e`（GEO-RESIDUAL），进入 RECOVER；用转移矩阵给需求后验加先验（人可能改了任务）。
- 重定位后，重新估计角色帧/绑定；若角色帧置信度低，回退 CHUNK-SERVO 的实例相对目标。
- 最大重试次数；超限则安全 hold/放弃，不碰撞。

### 3.8 表情查询与合规

#### 3.8.1 查询调度

```python
def maybe_query_affect(obs):
    if not self.affect_enabled:
        return None
    if self.t - self.last_affect_t < self.affect_period:  # e.g. 15 frames = 0.5s
        return None
    if not self.human_visible(obs):
        return None
    if not (self.ambiguous(self.w) or self.phase == "CONTACT"):
        return None
    return self.vlm_expression_probs(obs.head_image)  # same checkpoint
```

- 频率 ≤2 Hz；异步；不阻塞 5 步伺服。
- 只在需求歧义/接触阶段查询；正常执行不查。
- 同一 VLM checkpoint，文本提示 `"positive facial expression" / "neutral" / "negative"`，取 logits；不加载第二套权重。
- 如果 VLM 的零样本 FER 校准不过，自动关闭。

#### 3.8.2 校准与限幅

- 在内部小数据集（同意者、不同光照/头部姿态/遮挡）上测三分类 balanced accuracy 和 ECE。
- 用温度缩放 + 混淆矩阵校准；输出 `C_{a,s}`。
- 对数似然比上限 `log 3`；多帧用 Beta-Binomial 聚合，不单帧翻盘。
- 若校准门不过：`affect_enabled=False`，只用 C1 离线标签。

#### 3.8.3 隐私/伦理

- 不存人脸图；只存表情类别概率和时间戳；会话结束删除。
- 不做身份识别、不做情绪画像、不用于对人的评价。
- 需要同意/opt-out；评测人不愿意时关闭。
- 表情只影响机器人的确认/让行，不改变任务评分。

### 3.9 动作适配（WLA 54D → 挑战赛 21D）

```text
WLA 54D:
  left_ee_rel[6], left_gripper[1], left_hand[6],
  right_ee_rel[6], right_gripper[1], right_hand[6],
  waist[3], torso[3], base_vxvy[2], base_wz[1],
  base_pose_rel[6], height[1], left_leg[6], right_leg[6]

挑战赛 ee 21D:
  left_ee_abs[6], right_ee_abs[6],
  left_gripper[1], right_gripper[1], pivot[7]
```

映射：

1. `left_ee_abs = compose(T_base_ee_left_current, exp(left_ee_rel))`；转 xyz+rpy。
2. `right_ee_abs` 同理。
3. gripper 直通（按挑战赛的 0–1 方向校验）。
4. `pivot = [vx, vy, wz, yaw, pitch, roll, height]`，从 WLA base/waist 组合；符号/顺序必须用 `example_env.py` 和单任务通道验证。
5. 腿部/灵巧手在挑战赛 `ee` 模式下不直接下发；若 `pivot` 需要下身体，按官方 WLA server 的 `action.pivot` 语义映射。

**关键细节**：WLA 的每个未来动作是「相对 plan-time 当前 EE」的位姿；adapter 必须先把整个 30 步 compose 成 base 系绝对目标，再按 5 步切片。否则切片后的第 6–30 步会以错误锚点解释，产生系统性偏移。

**帧/TCP 风险**：WLA 的 EE 帧与挑战赛的 `*_ee_pose_gripper_base` 帧可能差一个 TCP/夹爪长度偏移；必须用 `example_env.py` 的观测和真实数据做一次手眼/工具坐标校准（平移 ≤1cm、旋转 ≤2°）。这是 G12 的第一验证项。

## 4. 复杂度分析

### 4.1 离线

- 相位分割/谓词标注：`O(N_ep · L · P)`，`N_ep=33,276`，`L` 为平均相位数（约 3–5），`P ≤ 10`。
- 需求库聚类：`O(N_ep · K · P)`；`K` 为每任务原型数（≤8）。
- 检索索引：ANN 构建 `O(N log N)`；存储 `<10 MB`（不含图像）。
- 角色目标库：每任务每相位每角色存一个 `SE(3)` 模板 + 协方差；`O(32·5·4)`，可忽略。
- 目标图/关键帧缓存：若存 20–40k 张 128×128 JPEG，约 200–400 MB；可随提交包分发或预加载。

### 4.2 在线

每个 5 步执行块的 CPU 开销：

| 模块 | 复杂度 | 典型开销 |
|---|---|---:|
| 角色绑定 | `O(n^3 + nR)`，n≤20 | 缓存后 <1 ms；重算约 2–5 ms |
| 需求滤波 | `O(K^2 P)`，K≤16，P≤10 | <1 ms |
| 目标选择 | `O(KG)`，G≤5 | <0.5 ms |
| 伺服 | `O(1)` 6D | <0.1 ms |
| 谓词评估 | `O(P)` 几何 | <1 ms |
| 表情查询（可选） | `O(C_VLM)`，≤2 Hz，异步 | 50–200 ms，但不阻塞 |

- 视觉感知（分割/深度/角色帧）是主要开销，约 10–30 ms；仍可在一个 167 ms 执行块内完成。
- VLA 推理异步；plan 过期用旧 plan + 伺服；冷启动同步一次。
- 总 CPU 附加 <5 ms；不会把 5 步块拖成 30 步块。

### 4.3 延迟预算

```math
T_{\text{fb}} \approx \frac{H_c}{f_c} + \tau + T_{\text{need}},
```

- `H_c=5`，`f_c=30Hz` → 167 ms；
- `τ` 为 RTT/推理/图像传输；`T_need` 为需求层 CPU（<5 ms，可忽略）；
- 若 `τ=50ms` → ~217 ms；`τ=150ms` → ~317 ms；
- 表情查询不进入 `T_fb`，因为它异步且低频；但会占 GPU，需要与 VLA 批处理/限流。

### 4.4 内存

- 需求图/模板：<10 MB；
- 目标图/关键帧：200–400 MB（可选，可只存 ROI）；
- 每端口状态：`O(KP + n)`，<1 MB；
- 共享 VLA：6B bf16 约 12 GB；一张 24 GB/40 GB GPU 可服务多个端口，具体并发取决于 batch/序列长度。

## 5. 正确性论证

### 5.1 假设

- **A1（候选完备）**：真实需求 `z*` 在候选集 `Z_t` 中。
- **A2（观测条件独立）**：给定 `z`，各帧的谓词/表情观测条件独立（实际有相关性；用分块/有效样本数近似）。
- **A3（可辨识）**：对任意 `z ≠ z*`，单帧 KL 散度 `D_KL(p(·|z*) || p(·|z)) ≥ D_min > 0`。
- **A4（校准）**：表情似然在使用前经过校准；否则权重为 0。
- **A5（角色帧有界）**：角色绑定正确时，`d(T_role, T_role^*) ≤ ε_r`；模板误差 `≤ ε_g`。
- **A6（伺服稳定）**：增益在 CHUNK-SERVO 的稳定域内；扰动有界。
- **A7（感知有界）**：谓词检测器有已知敏感度/特异度；角色绑定错误率 `≤ β`。

### 5.2 命题 1：需求后验一致性

**命题 1.** 在 A1–A4 下，若转移 `ε=0`，则

```math
\mathbb P\left(w_{z^*}(t) \le \frac12\right)
\le (K-1)\exp(-t D_{\min}),
```

其中 `D_min = min_{z≠z*} D_KL(p(·|z*)||p(·|z))`。若 `ε>0`，后验误差有一个 `O(ε/D_min)` 的偏差项；若表情模型失校准导致 `D_KL<0`，上述界失效，必须关闭/限幅。

**证明草图.** 对数后验比 `log(w_{z^*}/w_z)` 是独立对数似然比之和，期望为 `t D_KL`。由 Chernoff 界，`P(log ratio ≤0) ≤ exp(-t D_KL)`；对 `K-1` 个备选做 union bound。转移 `ε` 使后验成为有偏随机游走；用 Dobrushin 系数/标准 HMM 稳定性可得偏差项。表情通道的 KL 散度只有在校准正确时才为正；限幅 `log 3` 限制了最坏单帧影响，校准门保证期望信息非负。∎

**注**：A2 在视频上不严格成立（相邻帧高度相关）。实际用「每 N 帧一个有效样本」或「块 bootstrap」估计有效样本数；报告置信区间，不把 `t` 当真实独立样本数。

### 5.3 命题 2：角色相对目标误差界

**命题 2.** 在 A5 下，若角色绑定正确，则

```math
d(T_{\text{goal}}, T_{\text{goal}}^*) \le \varepsilon_r + \varepsilon_g.
```

若角色绑定错误，误差无上界。

**证明.** `T_goal = T_role g`，`T_goal^* = T_role^* g^*`。由左不变度量的三角不等式：

```math
d(T_role g, T_role^* g^*) \le d(T_role g, T_role^* g) + d(T_role^* g, T_role^* g^*)
= d(T_role, T_role^*) + d(g, g^*) \le ε_r + ε_g.
```

第二个等号用左不变性 `d(A g, B g)=d(A,B)`。若绑定错误，`T_role` 是另一个物体的角色帧，`d(T_role, T_role^*)` 不再有界；所以角色绑定必须进入需求后验，不能假设正确。∎

### 5.4 命题 3：伺服输入-状态稳定

**命题 3.** 考虑延迟 `d=0` 的离散误差动力学

```math
e_{k+1} = (1 - K H_c) e_k + d_k,\qquad \|d_k\| \le d_{\max}.
```

若 `0 < K H_c < 1`，则

```math
\|e_k\| \le (1 - K H_c)^k \|e_0\| + \frac{d_{\max}}{K H_c}.
```

若 `1 \le K H_c < 2`，收缩因子是 `K H_c - 1`，ISS 增益是 `1/(2-K H_c)`；仍稳定，但常数更大。

对延迟 `d=1`，特征方程 `z^2 - z + K H_c = 0`；若 `0 < K H_c < 1`，根在单位圆内，仍有 ISS 界（常数更大）。一般 `d` 用 CHUNK-SERVO 的特征方程/增益调度。

**证明.** 令 `V_k = ||e_k||^2`；展开 `V_{k+1} ≤ (1-KH_c)^2 V_k + 2(1-KH_c)||e_k||d_max + d_max^2`；由归纳/比较引理得界。延迟情形用特征根/线性系统 ISS 标准结论。∎

**注**：扰动 `d_k` 包括角色/模板误差、相机噪声、人为编辑。如果 `d_max` 超过任务容差，伺服不能保证成功；需求监控不能宣布完成。

### 5.5 定理：误成功界

**定理.** 在 A1–A7 下，设：

- 在角色绑定正确的条件下，需求后验 commit 到错误谓词图的概率 `≤ δ`；
- 角色绑定错误的概率 `≤ β`；
- 谓词检测器把假谓词判真的概率 `≤ η`。

则算法在真实需求未满足时宣布成功的概率 `≤ min(1, δ + β + η)`。

**证明.** 算法宣布成功需要 `φ_ẑ(S_t)` 为真且 commit。若真实需求 `z*` 未满足但算法宣布成功，则要么 `ẑ ≠ z*`（绑定正确时概率 ≤δ，绑定错误时概率 ≤β，合计 ≤δ+β），要么 `ẑ=z*` 但某个谓词被误判为真（概率 ≤η）。Union bound 得 `min(1, δ+β+η)`。∎

**注**：这是误成功界，不是成功率下界。真实成功率还取决于伺服收敛、谓词检测敏感度、任务难度；需要 G11 真机 A/B 验证。

### 5.6 推论：歧义安全终止

**推论.** 若 `w_max < 1-δ` 或 `H_n > θ_H`，算法不满足终止条件，因此不会宣布成功；它只能 probe、继续执行或 hold。

**证明.** 终止条件显式要求 `w_max ≥ 1-δ` 且 `H_n ≤ θ_H`；由构造，歧义状态不满足。∎

这条推论是本轮的安全底线：**宁可超时/不完成，也不在需求不确定时误报成功。**

### 5.7 不能证明什么

- 不能证明任意未见物体的角色帧可估计；只给出条件界和留一物体测试。
- 不能证明表情在真实评测中可用；只能校准/门控/关闭。
- 不能证明需求图与官方评分完全一致；94 个评分步骤只是粒度先验。
- 不能证明 sim-to-real 成功；仿真只用于机制/稳定域。
- 不能证明 +10pp；那是 G11 的实验目标，不是定理。

## 6. 实验设计与结果

### 6.1 E0a 合成：需求消歧（B）

**目的**：隔离「表情弱证据」对需求识别的作用，验证收益与校准风险。

**设置**：

- 两个候选需求在几何上完全相同；只有人类满意度能区分。
- 真实需求满足度 `s_true(t) = 1 - exp(-t/5)`，`t=1..24`。
- 错误孪生需求的预测满足度 `0.20 · s_true(t)`。
- 表情三类 `{neutral, positive, negative}`，生成模型：

```text
p_pos = 0.02 + 0.90 s
p_neg = 0.90 (1-s) + 0.02
p_neu = 1 - p_pos - p_neg
```

- 每帧以概率 `ρ` 有人在场；不在场时视为 missing（似然 1）。
- 比较：无表情、校准表情、失校准表情（`s→s+0.30`，平方锐化）、反相关表情（`s→1-s`）。
- `T=24`，`N=30,000` 合成 episode；MAP 需求准确率；随机猜测 0.5。

**结果**：

| 人在场率 ρ | 无表情 | 校准表情 | 失校准表情 | 反相关表情 |
|---:|---:|---:|---:|---:|
| 0.2 | 0.500 | **0.589** | 0.586 | 0.405 |
| 0.4 | 0.500 | **0.679** | 0.666 | 0.312 |
| 0.6 | 0.500 | **0.767** | 0.748 | 0.215 |
| 1.0 | 0.500 | **0.942** | 0.914 | 0.028 |

**读法**：

- 校准表情在歧义场景里显著提升需求识别；ρ=0.6 时 +26.7pp。
- 失校准仍有部分收益，但被侵蚀；反相关通道会把准确率压到机会水平以下。
- 这支持「表情只做弱证据 + 校准门 + 限幅」的设计；不支持「表情当控制器」。

**边界**：合成实验假设 `p(a|s)` 与生成模型同族；真实 FER 的跨人/跨文化偏差未建模。因此这是机制验证，不是真机收益证据。

### 6.2 E0b 合成：角色相对目标（B）

**目的**：验证「实例绝对目标 vs 角色相对目标」在物体位姿/形状变化下的误差，以及角色绑定错误的影响。

**设置**：

- SE(2) 简化：物体角色偏移 4 cm / 90°，目标相对角色 2 cm。
- 训练物体位姿为单位阵；测试物体位姿平移 `N(0,5cm)`、旋转 `N(0,10°)`。
- 角色帧估计噪声 `N(0,3mm)`、`N(0,2°)`。
- 实例绝对目标：直接复用训练时绝对目标，不随测试物体变化。
- 角色相对目标：`T_role(test) · g_template`。
- 角色绑定错误：以概率 `p_bind` 选到 10–30 cm 外的干扰物。
- `N=50,000`；误差相对真实测试目标。

**结果**：

| 方法 | 平移误差均值 | 平移 p95 | 旋转误差均值 | 旋转 p95 |
|---|---:|---:|---:|---:|
| 实例绝对目标 | **62.8 mm** | 122.2 mm | **7.97°** | 19.54° |
| 角色相对目标 | **3.8 mm** | 7.5 mm | **1.60°** | 3.92° |
| 角色相对 + 2% 绑定错误 | 8.8 mm | 8.0 mm | 1.91° | — |
| 角色相对 + 5% 绑定错误 | 16.9 mm | 11.5 mm | 2.40° | — |

**读法**：

- 物体位姿/实例变化下，角色相对目标把平均平移误差从 62.8 mm 降到 3.8 mm；这是「物体泛化」的数学来源。
- 但角色绑定错误会把误差拉回 8.8–16.9 mm；5% 绑定错误就足以吃掉大部分收益。所以角色绑定候选/验证是必需项，不是可选项。

### 6.3 E1 离线：33k 演示上的需求识别（计划）

**数据**：32 任务，33,276 episodes；先做 5 个 A 档任务（HangCup、PlugInEthernet、ZipUp、StackBowls、Unlock），再扩到 19 个 A 档。

**标注**：

- 相位：FACT-VLA CPT + 人工抽检；
- 角色绑定：物体槽位 + 角色标签；
- 谓词：每个相位 1–3 个谓词；容差用成功演示 95 分位；
- 需求图：每任务 2–4 个候选（含歧义孪生），由不同演示/人工构造。

**划分**：按 session/物体/背景分组；相邻帧不跨 split；留一物体（leave-one-object-out）。

**指标**：

- 需求 top-1/top-3 准确率；
- 歧义检测 AUROC（熵 vs 真实是否歧义）；
- 角色绑定准确率；
- 角色帧误差（平移/旋转）；
- 目标实例化误差；
- 谓词 precision/recall。

**基线**：

1. 语言先验 + 任务级固定模板；
2. CHUNK-SERVO DG-KEYFRAME（实例相对目标/目标图）；
3. 无表情 vs 离线表情弱标签；
4. 单绑定 vs top-m 绑定。

**门**：G8（top-1≥0.80，AUROC≥0.85）、G9（角色帧 ≤8mm/3°，绑定 ≥95%）。

## 7. 风险与合规

### 7.1 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 表情不可见/不可靠 | AFFEC 无收益甚至有害 | 默认关闭；校准门；限幅；反相关检测；核心不依赖 |
| 隐私/伦理 | 评测人反感/违规 | 不存图、不识别身份、需同意、可 opt-out |
| 需求图标注成本/主观性 | 需求库偏差 | 先做 5 个 A 档；半自动标注 + 人工抽检；用成功演示 95 分位定容差 |
| 角色绑定错误 | 目标错，误差无界 | top-m 绑定；margin 门控；probe；绑定不确定时回退 |
| 未见物体角色帧不可估 | RRG 失效 | 只对可辨识刚体启用；透明/反光/变形回退 VLA |
| 单模型解释 | 被判定第二个模型 | C1 离线/C2 确定性/C3 同 checkpoint；提交材料写清楚 |
| 延迟 | 5 步块被拖慢 | 需求层 CPU <5ms；表情异步 ≤2Hz；VLA 异步；p99 门 |
| 评测噪声 | +1–2pp 假阳性 | 配对 A/B、bootstrap、重复实验；320 trials SE≈2.4pp |
| 仿真到真机 gap | 仿真结论不成立 | 仿真只做机制/稳定域；真机单任务门 |
| 需求图与官方评分不一致 | 优化错目标 | 单任务通道验证；用 94 个评分步骤做粒度先验，不做硬假设 |
| 透明/反光/变形 | 几何/角色帧失败 | 可辨识性门控；腕部 2D/图像回退；变形任务不启用 |
| 数据泄漏 | 离线指标虚高 | 按 session/物体/背景分组划分；相邻帧不跨 split；留一物体 |
| `pivot` 语义不一致 | 动作被拒/机器人不动 | 先用 `example_env.py`/单任务通道验证；保留零 pivot 回退 |
| 提交次数限制 | 无法多次 A/B | 邮件确认；单任务通道先验证；一次提交则保守 |
| 安全 | probe/恢复碰撞 | 安全动作集；限速/限幅；最大重试；歧义时 hold |

### 7.2 单模型合规

| 模式 | 做法 | 风险 | 建议 |
|---|---|---|---|
| **C1 离线** | FER 只离线打弱标签；线上只用语言/演示/几何 | 最低 | **默认** |
| **C2 确定性** | 线上只用几何/语言/演示；表情完全不用 | 低 | 评测人不稳定时 |

### 7.3 隐私/伦理

- 不存人脸图像；只存表情类别概率和 `t`。
- 不做身份识别、不做情绪画像、不用于对人的评价/惩罚。
- 需要知情同意/opt-out；评测人不愿意时关闭。
- 表情只影响机器人的确认/让行，不改变任务评分。
- 如果官方禁止任何面部分析，直接走 C2。

### 7.4 安全

- probe 动作限制在安全集：速度/位移/力矩上限；不靠近人；不进入不可逆状态。
- 歧义时 hold 优先于猜测；最大重试次数；超限安全放弃。
- 恢复时先停、再重定位；目标不可见时 VLA 重规划，不盲动。
- 任何异常返回合法 hold，不返回 NaN/错误形状。

## 8. 与第 10–12 轮的关系

### 8.1 保留

- FACT-VLA 的相位化 BC、CAC 柔顺执行、EGP 证据门控；
- GEO-RESIDUAL 的动作条件化残差、米制表面距离、编辑检测；
- CHUNK-SERVO 的 30 步规划 + 5 步伺服、DG-KEYFRAME 相对目标、官方 WLA 基座；
- 官方 rubric、33k 演示、单任务通道。

### 8.2 升级

- 目标层：从「检索到的实例相对位姿」升级为「角色帧实例化的需求谓词目标」；
- 完成判据：从「plan 结束/视觉误差小」升级为「谓词满足 + 需求后验 commit」；
- 泛化：从「位置/背景泛化」升级为「角色/affordance 物体泛化」；
- 人机：从「编辑检测/恢复」升级为「可选表情弱证据 + social probe」；
- 歧义：从「默认目标唯一」升级为「需求后验 + probe/maximin + 安全终止」。

### 8.3 剪枝

- 不做第二个学习模型/FER 产品；
- 不做 6D 物体位姿网络；
- 不做完整 sim-to-real 策略训练；
- 不做 30Hz 广域网伺服；
- 不做力/触觉闭环（API 没有）；
- 不逐任务训策略；
- 不把榜单任务排名当难度表。
