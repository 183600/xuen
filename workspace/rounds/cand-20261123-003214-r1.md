# 第 4 轮（灵感驱动研究循环·新灵感二元组第 1 轮；本轮灵感：「步骤分」×「开源生态」）

> **基线**：第 3 轮产出 MetricVoiceGauge-NCD-HUTDH-v21 + IP-425–430（语义-规范层：SDC/CAC/DCL/GIC/HPC+/CFC+；其上承 v20 联邦感知证书 PCA/CTS/CFC/HPC/CFCtrl 与 v19/v17 全部模块）。
> 本轮纪律：**安全不是二元的，而是可加、可标定、可复算的信用；模块不是黑盒，而是带血缘、可复现、可版本化的包**。不推倒 v21：SDC/CAC/DCL/GIC/HPC+/CFC+ 与 v20/v19/v17 全部保留。本轮只做一件事：**把 v21 的二元准入门 HPC+ 升级为「步骤分证书代数 + 开源模块生态」，用分级信用赎回 v21 过度保守的活性，同时把"可审计"从叙事变成可机械复算的供应链证明**。

## 0. 直觉与动机

**灵感 1（步骤分 → 安全是可加的信用，不是对错的判卷）**
直觉：v21 的 HPC+ 是"判卷只给满分或零分"——AbsCert 签发就放行、拒发就全域保守（活性坍缩）；检测器一故障就整体退回 v20。可人类批改证明题是**按步骤给分**的：某一步没证出来，不等于整题零分，只扣那一步的分。安全也一样：几何安全、覆盖负信息、合规、意图、模态多样性、时序持续……是若干可独立核查的"步骤"，每步都在为同一个安全目标贡献**可标定的信用**。当某步证据弱或缺失，不该整体保守，而应按缺的步骤**精确扣分**，得到一个更小但非零的可执行域——这正是 v21 最大痛点（保守性叠加导致活性坍缩）的结构性解药。
**严谨定义（步骤与信用）**：设步骤基 `S={s_1..s_m}`，证据 `e_i∈E_i`，每步信用 `γ_i: E_i×Γ_i → [0,w_i]`，并标定满足"若该步的安全断言在真实世界失败，则 `E[γ_i] ≤ δ_i·w_i`"。证书 `Cert=(e, D, γ, manifests, C, Θ_C)`，其中 `D=(S,E_D,ρ)` 为依赖图，`ρ_ij∈[0,1]` 为"共败相关"上界；聚合信用 `C = Σ_i γ_i − Σ_{(i,j)∈E_D} ρ_ij·min(γ_i,γ_j)`；准入族 `{Θ_c}` 满足 `c_1≤c_2 ⇒ Θ_{c1}⊆Θ_{c2}`，安全界 `ε(c)` 单调不增。
**反直觉点**：**安全继承不一定要"子集"，只要"可证"**——v22 不必是 v21 的子集；它可以嵌在 **v20 的几何安全边界**与**v21 的过度保守**之间，用每一分信用附带一张针对 v20 边界的安全证明来"赎回"活性。未知/未标定的情形一律退回 v21，于是 `Exec_v21 ⊆ Exec_v22 ⊆ Exec_v20`（而非 ∀旧版的子集包含）。这是把前几轮"有偿赎回保守空间"从二元（AbsCert）推广为分级。

**灵感 2（开源生态 → 证书是一条可复现、可审计的供应链）**
直觉：现代安全栈由大量第三方件拼成（检测模型、标定数据集、规则包、传感器驱动），开源生态早已用一套成熟机制解决"规模化信任"：语义化版本、依赖清单 (SBOM)、可复现构建、签名来源证明 (provenance / SLSA / in-toto)、许可证兼容。v21 号称"可审计"，但审计的是**结果**，不是**来历**：它回答不了"这张 AbsCert 是哪个模型版本、哪份标定集、哪版规则编出来的，能否在另一台机器上逐位复算"。把开源生态机制移植到证书上，"可审计"才落地为**可机械复算的供应链证明**。
**严谨定义（模块清单与可复算）**：模块清单 `M=(mid, semver, deps, license, artifact_hash, provenance)`；证书携带传递依赖闭包 `SBOM=closure(deps)`；信任权重 `t(M)∈[0,1]` 封顶该模块可计入的信用 `w_i ≤ t(M)·w_max`。`RCR(Cert)` 以 `(SBOM, cached_outputs_hash, calibration_table, rule_closure_hash)` 为输入**确定性重放决策**，输出须与证书记录逐位一致，否则证书无效。
**反直觉点**：**在开源生态里，供应链就是攻击面**——被投毒的检测权重、被篡改的规则包，等价于对整张安全证书的"后门"。因此模块血缘与许可证兼容不是工程细节，而是**安全的一等公民**，直接决定某一步骤分能否计入。

**两者如何统一**
步骤分定义"如何给安全打分"，开源生态定义"每一分由哪个可复现、可追溯的模块产出"。统一为 **v21 之上的"步骤分-开源生态"层**：`SCCA` 把 HPC+ 从二元门升级为信用域族 `{Θ_c}`；`PAMR/RCR` 保证每一分信用的来源与可复算性；`CWA`（信用化缺席）把 v21 押在经验召回下界 `κ_c` 上的二元 AbsCert 拆成多步独立负证据的信用、并保留手势硬地板；`SMUG` 用语义化版本的"单调升级契约"守住升级不引入回归。统一准入门升级为 **HPC++ = (Θ_C, SBOM 验证, RCR 复算, 硬地板)**，产出的执行集被夹在 `Exec_v21 ⊆ Exec_v22 ⊆ Exec_v20`——不是回到 v21 的死板，也不是越过 v20 的几何红线，而是**用可证信用赎回 v21 的过度保守**。

## 1. 研究问题（轮次升级版）

- **Q1（信用的标定与相关性）**：如何标定每步 `γ_i` 与相关上界 `ρ_ij`，使折扣后的 `C` 是"独立信用"的保守下界？"未知依赖默认 `ρ=1`"的保守先验与活性赎回之间如何权衡？相关性折扣在何种情形会高估（漏扣）或低估（误扣）真实相关？

- **Q2（信用赎回与 v20 夹层）**：如何定义"赎回区" `Refund ⊆ Exec_v20 \ Exec_v21`，并为其中每个计划附一张针对 v20 HPC 的安全证明？`Exec_v21 ⊆ Exec_v22 ⊆ Exec_v20` 的夹层何时最紧？如何防止"信用洗白"——若干弱步骤的信用相加冒充一个强证明？

- **Q3（来源与可复算）**：如何定义 manifest / SBOM / provenance，使 RCR 在 ML 推理本身非确定的前提下仍能**逐位复算决策**？可信计算基 (TCB) 如何界定？许可证兼容与信任等级如何封顶信用权重 `w_i`，以及多厂商异构信任如何组合而不被单个恶意厂商抬高总分？

- **Q4（升级单调与联邦生态）**：在什么契约下，一个 patch 升级可被证明为"信用不膨胀、决策不漂移"？如何在生态规模上跑差分信用回归？minor/major 升级的重标定/重认证边界如何界定？模块 fork/rebase 后血缘如何重锚？

## 2. 设计原则（在 P34–P36 基础上新增 P37–P39）

**P37 步骤分守恒律（Step-Credit Conservation）**
信用只能由**已标定且已认证独立**的步骤累加：`C = Σγ_i − Σ_{(i,j)∈E_D} ρ_ij·min(γ_i,γ_j)`，`ρ_ij` 为共败相关上界；**未认证依赖对默认 `ρ=1`**（完全相关，零净加分）。任何一分信用必须附一张针对 v20 边界的安全证明；无证明 → 该步信用记 0 → 退回 v21。故信用只"赎回"，不"凭空创造"。

**P38 模块血缘可溯律（Provenance-Bound Modules）**
每一分信用都绑定一个 PAMR manifest：SBOM 可解析、provenance 链可验、许可证兼容、`w_i ≤ t(M)·w_max`。任一失败 → 该步信用为 0。patch 升级须携带"信用不膨胀 + 金标决策一致"契约，否则拒绝。

**P39 可复算即有效律（Reproducible-is-Valid）**
证书有效 ⟺ `RCR` 能由 `(SBOM, cached_outputs_hash, calibration_table, rule_closure_hash)` 确定性重建与记录逐位一致的决策。不可复算 → 证书无效 → 退回 v21。模型推理不重跑，但其输出以哈希作为冻结输入，使"决策层"完全可复算。

## 3. 与基线的接口（如何退化）

- 仅单检测步骤 / 依赖未知（`ρ=1`）/ 模块未验证 / 不可复算 / 标定漂移 → 一律退回 v21（不是 v20）：`Exec_v22 = Exec_v21`（最坏情形）；
- 恶意/被投毒模块 → 信任封顶 `t=0` → 该步信用 0 → 被排除（引理 166）；
- CWA 手势硬地板触发 → 该区缺席信用强制归零，不可被其它弱步骤"补贴" → 等价 v21 AbsCert 拒发（引理 165）；
- SMUG 拒绝升级（patch 信用膨胀/决策漂移）→ 保持旧模块 → 执行域不扩大；
- SCCA/PAMR/RCR 全失效 → 完全回退 v21 ⇒ `Exec_v21 ⊆ Exec_v22 ⊆ Exec_v20 ⊆ Exec_v19 ⊆ Exec_v18`（引理 168）。
- **安全继承（夹层版）**：v22 的每一条执行要么本就是 v21 的执行，要么携带针对 v20 HPC 的信用证明；信用**永不绕过 HPC 几何门**，只重调 v21 叠加的软约束（速度/人距/缺席假设/义务过滤）。故上界是 v20，下界是 v21。

## 4. 预期贡献

1. **分级安全代数**：首次把二元准入证书升级为"步骤基 + 已标定信用 + 单调准入族"的可加证书代数 `SCCA`，给出 `Θ_c` 的单调性与安全界 `ε(c)`；
2. **相关性折扣（NMS 去重的信用版）**：把 v21 的"空间证据去重"推广为"步骤依赖去重"，用 `ρ` 上界 + 未知即 `ρ=1` 的保守先验，结构性防"信用洗白"；
3. **来源即安全**：`PAMR + RCR` 让每张证书都成为可追溯、可逐位复算的供应链对象，把"可审计"从叙事变成可机械验证；
4. **信用化缺席**：把 AbsCert 押在单一 `κ_c` 的经验赌注拆成多步独立负证据的联合信用，直接削弱 v21"缺席幻觉"的单点失效；
5. **语义化单调升级**：给出 patch 的"信用不膨胀 + 决策不漂移"契约，minor 重标定、major 重认证；
6. **v20/v21 夹层定理**：给出 `Exec_v21 ⊆ Exec_v22 ⊆ Exec_v20` 的安全夹层，把"赎回保守"从二元推广为分级，且残余相关 `η` 显式进入风险项。

## 5. 本轮最大风险

**一句话**：步骤分把"安全"从二元证书变成可加信用，但信用只有在"各步骤独立且已标定"时才守恒；开源生态里模块普遍共享血缘（同源模型/同厂传感器/同数据集/同标注者），相关性未被识别时各步会一起错、一起加分，机器人将带着一张高分、可复算、可审计的证书撞上所有步骤共同看不见的人——即"信用通胀式假安全"。

```python
# IP-431 步骤分证书代数（SCCA）
class StepCreditAlgebra:
    def __init__(self, basis, credit_fns, dependence, domain_family,
                 conservative_prior=True):
        self.S = basis                  # 步骤基 {s_i}
        self.gamma = credit_fns         # γ_i: E_i×Γ_i -> [0, w_i]（已标定）
        self.D = dependence             # 依赖图 D=(S,E_D,ρ)
        self.domains = domain_family    # 单调族 {Θ_c}，c↑⇒域↑
        self.conservative = conservative_prior   # 未知依赖默认 ρ=1

    def _rho(self, i, j):
        if (i, j) in self.D.edges:
            return self.D.edges[(i, j)]            # 已认证的共败相关上界
        return 1.0 if self.conservative else 0.0    # 未知 -> 完全相关（保守）

    def aggregate(self, evidence, trust):
        """相关性折扣：把"一起错"的部分只算一次（NMS 去重的信用版）"""
        credits = {i: self.gamma[i](evidence[i], trust) for i in self.S}
        C = sum(credits.values())
        for i in self.S:
            for j in self.S:
                if i < j:
                    C -= self._rho(i, j) * min(credits[i], credits[j])
        return max(C, 0.0), credits

    def certificate(self, evidence, trust, manifests, proofs):
        C, vec = self.aggregate(evidence, trust)
        theta = self.domains.at(C)          # 单调：C 越大域越大
        return StepCert(credits=vec, C=C, theta=theta,
                        sbom=closure(manifests), proofs=proofs)


# IP-432 来源锚定模块注册表（PAMR）
class ModuleRegistry:
    def __init__(self, policy):
        self.policy = policy            # 许可证兼容集 + 信任等级策略
        self.mods = {}

    def resolve(self, root):
        """解析依赖闭包 -> SBOM；缺失/环/许可不兼容 -> 不可用"""
        sbom = dependency_closure(self.mods, root)
        if any(m.missing or m.license not in self.policy.allowed for m in sbom):
            return None
        return sbom

    def verify(self, manifest):
        # 哈希匹配 ∧ provenance 链签名可验 ∧ 许可证兼容
        return (hash_ok(manifest)
                and verify_provenance(manifest.provenance)
                and license_ok(manifest, self.policy))

    def trust_weight(self, manifest, w_max):
        # 信任封顶：未审计社区模块拿不满信用
        return min(manifest.trust_level, 1.0) * w_max


# IP-433 可复算证书重建（RCR）
class ReproducibleRebuild:
    def rebuild(self, cert):
        # ML 推理不重跑；只以哈希冻结的输出重放"决策逻辑"（逐位确定）
        inputs = (cert.sbom, cert.cached_outputs_hash,
                  cert.calibration_table, cert.rule_closure_hash)
        recomputed = deterministic_decision(inputs)
        return recomputed.decision == cert.decision    # 不等 -> 证书无效


# IP-434 信用化缺席（CWA）
class CreditWeightedAbsence:
    def __init__(self, scca, gic):
        self.scca = scca
        self.gic = gic                  # GIC：人体在场独立证据通道

    def absence_credit(self, region, steps):
        # 负证据步骤：检测召回/几何覆盖/时序持续/跨机器人独立视点/手势缺席
        ev = {k: steps[k] for k in ABSENCE_STEPS}
        C, _ = self.scca.aggregate(ev, steps.trust)
        # 手势硬地板：任一有效手势 ⇒ 该区缺席信用必须归零（不可被补贴）
        if self.gic.human_present_near(region):
            return 0.0, "GESTURE_FLOOR"
        return C, "OK"


# IP-435 语义化单调升级门（SMUG）
class SemverMonotoneGate:
    def upgrade(self, old, new, regression):
        if new.semver.major != old.semver.major:
            return self.full_recert(new)              # major：全量重认证
        if new.semver.minor != old.semver.minor:
            return self.recalibrate(new)              # minor：重标定受影响信用
        # patch：必须证明"信用不膨胀"且金标决策一致
        if not regression.credit_non_increasing(old, new):
            return Reject("PATCH_CREDIT_INFLATION")
        if not regression.decisions_equal(old, new):
            return Reject("PATCH_DECISION_DRIFT")
        return Accept(new)


# IP-436 HPC++ / 开源步骤分栈
@dataclass
class HPCPlusPlus:
    step_cert: StepCert               # SCCA 信用证书
    sbom: list                        # PAMR 解析出的依赖闭包
    rebuild_ok: bool                  # RCR 复算通过
    floors_ok: bool                   # 硬地板（F 规则 / 手势在场）
    hpc: HierarchicalPerceptionCert   # v20 几何证书（永不被信用绕过）

    def admits(self, theta):
        # 信用只在 v20 几何域内"赎回"软约束，绝不越过 HPC
        return (self.hpc.contains(theta)            # 夹层上界：v20
                and self.rebuild_ok and self.floors_ok
                and theta in self.step_cert.theta)  # 夹层下界：v21 ∪ 信用
```

## 3. 推导

**引理 163（步骤分守恒/信用可靠性）** 设对每步 i，`γ_i` 已标定使"该步断言失败时 `E[γ_i] ≤ δ_i·w_i`"；设 `ρ_ij` 是第 i、j 步真实共败相关的上界，且未认证对取 `ρ_ij=1`。则折扣聚合 `C = Σγ_i − Σρ_ij·min(γ_i,γ_j)` 是"把各步视为独立时的信用"的**保守下界**（相关性只减分、不加分）。故以 `C` 索引的 `Θ_C` 相对任何已认证独立分解都不更大；`ρ` 高估只会使 `Θ_C` 更小（更保守），`ρ` 低估是不安全的唯一来源（见第 8 节残余相关 `η`）。∎

**引理 164（v20/v21 夹层安全）** 定义 `Refund = Θ_C \ Exec_v21`。HPC++ 要求 `hpc.contains(θ)`（v20 HPC 永不被信用绕过），且 `Refund` 中每个计划须附一张区域级安全证明，证明其相对 v20 几何+规范边界满足 `P(violation) ≤ ε(C)`。因此任意被 v22 准入的计划要么属于 `Exec_v21`，要么属于 `Exec_v20\Exec_v21` 且带 v20 级证明；故 `Exec_v21 ⊆ Exec_v22 = Exec_v21 ∪ Refund ⊆ Exec_v20`。信用只重调 v21 叠加的软约束（速度/人距/缺席假设/义务过滤），不改变几何碰撞判定。∎

**引理 165（信用化缺席的可靠性）** `A_reg` 为负证据步骤的折扣信用。手势硬地板：若 GIC 以 `q≥q_low` 判有人在场，则强制 `A_reg=0`，任何其它弱步骤都不得补贴——故不会出现"手势在场合仍签发缺席"。当仅保留 v21 的单一检测步骤且依赖未知（`ρ=1`）时，`A_reg` 退化为 v21 的二元 AbsCert（满足 `κ_c` 才给满分）。加入**已认证独立**的负证据步骤（几何覆盖、时序持续、跨机器人独立视点）只会增加 `A_reg`；任一负步骤标定失效则 `A_reg` 下降。于是"覆盖区有人 ∧ 判缺席"的概率不再由单一 `κ_c` 决定，而由所有已认证独立负步骤的**联合失败**决定，被 `η` 之外的折扣乘积界定。∎

**引理 166（来源与可复算的可靠性）** 若每个计入信用的模块都满足 `hash_ok ∧ verify_provenance ∧ license_ok`，且 `w_i ≤ t(M)·w_max`；且 RCR 在 `(SBOM, cached_outputs_hash, calibration_table, rule_closure_hash)` 上确定性重放决策并与记录逐位一致，则：任一张有效 v22 证书都可追溯到具体模块版本并可被独立复算；替换为未验证/不可复算模块使该步信用记 0，只会缩小 `Θ_C`。故来源验证失败或复用失败，方向恒为更保守。∎

**引理 167（语义化升级的单调性）** SMUG 要求 patch 升级满足 `γ'_i ≤ γ_i`（逐点信用不膨胀）且金标语料上决策一致；minor 触发受影响步骤重标定（信用可增，但须重新附 v20 级证明，等价于新增 `Refund` 证据）；major 强制全量重认证。故 patch 不扩大 `Θ_C`；minor/major 的扩张都必须重新走引理 164 的证明义务。任何绕过契约的升级即视为未验证模块（引理 166），信用记 0。∎

**引理 168（v22 整体安全/夹层与残余相关）** 同一几何快照、同一规则库与机器人集合、同一 SBOM 下：SCCA 只做相关性折扣（163）、HPC++ 永不绕过 v20 HPC 且赎回区带证（164）、CWA 手势硬地板与联合负证据（165）、PAMR/RCR 失败即缩域（166）、SMUG 升级不膨胀（167）。故 `Exec_v21 ⊆ Exec_v22 ⊆ Exec_v20 ⊆ Exec_v19 ⊆ Exec_v18`。设 `η` 为依赖图上界未捕捉的真实相关比例，则"信用通胀式假安全"的概率被 `(1−η)` 之外未覆盖的相关性界定；`η→0` 时信用严格守恒。∎

## 7. 已知风险与失效模式

1. **残余相关导致信用通胀**（最大风险，见第 8 节）：`ρ` 只上界了已识别的相关，`η` 未被识别部分会让多步一起错、一起加分。缓解：未知默认 `ρ=1`（E803）、血缘相似度检测（E809）、信用上界与交叉验证（E806）。
2. **单步信用标定失效**：`γ_i` 在分布漂移下不再满足失败上界，等于"错发信用"。缓解：在线漂移监控+信用衰减（E826）、`δ_i` 保形上界（E801）。
3. **依赖图上界低估**：`ρ` 估小会把相关步骤当独立，直接放大信用。缓解：`ρ` 零低估预注册（E802）、以最坏情形相关做敏感性分析。
4. **来源≠正确**：可复算、可追溯只保证"同样地算"，不保证"算得对"；签名恶意模块仍可正确复算地出错。缓解：信任封顶（E815）、投毒模拟（E825）、审计分级。
5. **信用洗白**：多弱步骤相加冒充强证明。缓解：折扣聚合（E804）、洗白攻击测试（E806）、`min` 折扣无法被拆小规避。
6. **语义化契约被绕过**：patch 藏入回归而"看起来单调"。缓解：差分回归（E816–817）、金标语料扩容。
7. **赎回区重新打开碰撞面**：若 v20 HPC 本身在某区域过紧假设，`Refund` 可能触及真实风险。缓解：`Refund` 逐计划带证（引理 164）、端到端零违例（E822）。
8. **复算与供应链成本**：SBOM 解析、来源验证、RCR 重放可能拖慢离线链路。缓解：全部离线化，控制路径只查 `Θ_C`（E827）；缓存与并行。

## 8. 本轮最大风险

**一句话**：步骤分把"安全"从二元证书变成可加信用，但信用只有在"各步骤独立且已标定"时才守恒；开源生态里模块普遍共享血缘（同源模型、同厂传感器、同数据集、同标注者），相关性未被识别时，各步会一起错、一起加分，机器人将带着一张高分、可复算、可审计的证书，撞上所有步骤共同看不见的人——**"信用通胀式假安全"**。
