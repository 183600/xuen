# 第 56 轮（承接第 55 轮语义-接触接地；灵感循环第 1 轮；本轮灵感：「需求洞察」×「伦理审查」）

> 第 55 轮把“分割标签”升级为“可执行的接触约束”，解决的是 **系统能不能做到**。本轮把问题前移到 **该不该做、为谁做、凭什么说做到了**：需求洞察把“用户想要”拆成可观测残差与可验收契约，伦理审查把“不能伤害、不能欺骗、不能剥夺退出权”从软约束提升为 **不可折现的硬否决**。核心矛盾：**H24**：需求是多主体、隐性、会漂移的，能力指标无法代表需求满足，且强势主体的需求会系统性淹没沉默主体；**H25**：伦理审查若被当作事后清单或被折成加权惩罚项，就会在优化中系统性侵蚀——伦理否决权不能被任务效用交换，其“零违反”只能是条件性制度结论，不能是概率声明。

## 0. 直觉与动机

**灵感 1（需求洞察 → 先建“需求证据台账”，再谈能力）**
直觉：用户不会为“语义分割”或“全身控制”付费，他们买的是“夜里起身不摔倒、不被摄像头盯着、不失去决定权”。需求洞察要从访谈、现场观察、事故/工单、遥测里抽取需求，并把它写成 **可观测残差 + 验收阈值 + 证据链**。更关键的是区分 **正需求**（要达成）与 **负需求**（绝不能发生，如隐私泄露、欺骗、强制接管、尊严受损）：前者是目标，后者是硬约束。能力若不能追溯到任何需求，就是“孤儿能力”，应删除而不是继续堆叠。

**灵感 2（需求洞察 → 不可判定的需求必须显式化为假设）**
直觉：一条不能被测量的需求不是需求，而是愿望或隐含假设。需求洞察的严谨性在于 **可判定性**：有没有可观测变量、估计器是否校准、阈值是否有操作定义、检验是否有统计功效。判不了的需求不能悄悄消失，必须写成带责任人、证据和到期时间的 **显式假设**。再用价值信息（VoI）决定下一条该访谈谁、该测什么，避免“无限访谈”。

**灵感 3（伦理审查 → 利益相关者风险台账，而非一张勾选表）**
直觉：伦理审查问的不是“系统有没有加隐私开关”，而是“谁可能受伤害、谁同意了、谁有权说不、出了事谁负责”。必须把用户、旁观者、照护者、操作员、未来用户都放进台账，记录物理伤害、隐私、自主性、公平、尊严、欺骗六个维度。有些约束是 **不可交易的**：对未同意第三方的物理风险、隐私侵犯、欺骗性交互、剥夺人工接管权，不能用“任务成功率更高”来补偿。

**灵感 4（伦理审查 → 运行时门与可逆性预算）**
直觉：伦理不能只在部署前审一次。上下文变了、同意撤回了、动作变得不可逆了，都需要运行时再判定。因此要有 **伦理运行时门**：只允许落在伦理可接受集内的动作；不可逆动作必须消耗可逆性预算并获授权；门为空时不是“优化一个折中”，而是安全停机并请求人类。伦理门必须 **fail-closed**（不确定即拒绝），并留下不可篡改的审计链。

**灵感 5（需求 × 伦理 → 联合可接受性核与双证据证书）**
直觉：物理可行、语义可信、需求满足、伦理可辩护是四个不同的集合。前两个是经验/概率问题，第三个是测量问题，第四个是规范/程序问题。部署集合是四者交集 `D = K(Σ) ∩ NeedSat ∩ Adm_E`。联合证书必须同时携带 **经验证据链**（残差、校准、漂移）与 **规范证据链**（同意状态、否决记录、审查独立性、问责与申诉通道），并明确列出未满足需求、未决冲突与少数派异议。

**灵感 6（需求 × 伦理 → 冲突仲裁与退出权，而非“多数投票”）**
直觉：需求会冲突：照护者想持续监控，老人想保留隐私；操作员想提高速度，旁观者想降低风险。伦理审查不是假装冲突不存在，而是提供 **合法仲裁程序**：硬约束优先，其次强制需求，最后才是可选效用；涉及基本权利的冲突不做功利投票。同意必须是一个 **可撤回的状态机**，退出成本要可测，退出后系统必须真的降级/停止相应功能。

## 1. 形式化定义（增量：定义 127–132）

**定义 127（需求台账与需求-残差可追溯矩阵）**
需求台账 `N = {n_i}`，`n_i = (s_i, t_i, φ_i, e_i, r_i, τ_i, ν_i)`：`s_i∈S` 提出/承受需求的主体；`t_i∈{功能,安全,可用,隐私,自主,尊严,公平,可维护}`；`φ_i` 需求陈述；`e_i` 证据链；`r_i(π,θ)` 可观测残差；`τ_i` 验收阈值；`ν_i∈{+,−}` 正/负需求。为保证方向一致，`r_i` 统一定义为 **不利残差**（越小越好）。记强制需求集 `N_m⊆N`、负需求集 `N^-⊆N`。
可追溯矩阵 `T_NE ⊆ N × R × C × E` 连接需求、残差、能力与证据。若能力 `c` 不在任何需求的路径上，称 **孤儿能力**；若需求 `n` 没有可观测残差，称 **孤儿需求**。需求覆盖
`cov(N,π,θ) = (1/|N_m|) Σ_{n∈N_m} 1[r_n(π,θ) ≤ τ_n]`，负需求违反 `viol(N^-,π,θ)=Σ_{n∈N^-} 1[r_n(π,θ)>τ_n]`，要求 `viol=0`。

**定义 128（需求可判定性、价值信息与漂移）**
`dec(n)=1` 当且仅当存在可观测 `o`、估计器 `r̂` 与校准界 `|r̂-r|≤ε_r`，且阈值 `τ_n` 有操作定义、检验在预算 `B_n` 下达到给定功效。不可判定需求转为显式假设 `a_n=(n, owner, evidence, expiry)`，不得静默丢弃。
价值信息 `VoI(n)=E[Δloss(n)]/cost(n)`，下一探针取 `argmax_{n: dec(n)=0} VoI(n)`。
需求漂移 `d_n(t)=|r_n(π_t,θ_t)-r_n(π_0,θ_0)|`；当 `d_n>δ_n`、上下文改变或同意状态改变时触发再征求。漂移监控的联合条件
`drift_ok(N,t) ⇔ ∀n∈N_m: d_n(t)≤δ_n`。

**定义 129（利益相关者伦理台账与不可交易约束）**
伦理台账 `E=(S,H,C,V,A,R)`：`S` 含用户、旁观者、照护者、操作员、未来用户；`H={h_j}` 为六维伤害向量（物理、隐私、自主、公平、尊严、欺骗）；`C` 为同意状态机 `c_s(data,action,t)∈{none,informed,limited,withdrawn,expired}`；`V` 为否决权（谁可对哪类动作/数据说不）；`A` 为问责角色与申诉通道；`R` 为审查机构的独立性/利益冲突记录。
伦理可接受：
`Adm_E(π,θ) = {π | ∀s: consent_s covers (data,action) ∧ veto_s(π)=0 ∧ h_s(π) ≤ H_s^hard}`。
其中 `H^hard` 对未同意第三方的物理与隐私伤害、欺骗性交互、剥夺人工接管权设硬上界；**这些约束不参与标量加权，任何 `utility - λ·harm` 的补偿都视为无效**。仲裁采用字典序：硬约束 ≻ 强制需求 ≻ 可选效用。

**定义 130（运行时伦理门与可逆性预算）**
伦理可接受动作集
`A_eth(x,θ) = {u∈A_WB | h_j(x,u)≤H_j^hard ∧ data_flow(u)⊆allowed(purpose) ∧ (irreversible(u)⇒authorized(u)) ∧ override_available}`。
门输出 `u* = argmin_{u∈A_eth} ||u-u_nom||²_W`；若 `A_eth=∅`，回退 `u_eth_stop`：安全停机、保持状态、请求人类，**不允许在伦理约束外做折中优化**。
可逆性预算 `B_rev(t)≥0`，不可逆动作消耗 `c_irr(u)`，仅人类授权可补充。审计链 `ℓ_t=H(ℓ_{t-1}, x_t, u_t, auth_t, consent_t)` 要求抗篡改。

**定义 131（需求-伦理联合可接受性核）**
`D(π,θ) = K(Σ) ∩ NeedSat(N,π,θ) ∩ Adm_E(π,θ)`，其中 `NeedSat` 要求 `cov(N_m)=1 ∧ viol(N^-)=0`。部署可接受条件
`deployable(π,θ) ⇔ K_margin≥θ_K ∧ cov(N_m)=1 ∧ viol(N^-)=0 ∧ Adm_E=1 ∧ drift_ok ∧ consent_valid`。
注意 `D` 不是概率集合：`K` 与 `NeedSat` 可由概率/测量支撑，而 `Adm_E` 是规范约束，不能被概率化后与任务效用交换。

**定义 132（需求-伦理联合证书 NEC）**
`J_ne=(N_core, R_cov, E_ledger, V_ok, A_audit, δ_n, ρ_ne, dissent, assumptions, evidence)`：
- `N_core` 核心需求及其证据链；`R_cov` 残差与裕度；
- `E_ledger` 利益相关者伤害/同意/否决/问责台账；`V_ok` 否决审计；
- `A_audit` 动作、授权、同意变更的不可篡改日志；
- `δ_n` 需求漂移与启发不确定性；`ρ_ne(ε)=inf_{||θ-θ̂||≤ε} P(NeedSat∧Adm_E|θ)` 联合鲁棒性；
- `dissent` 少数派异议与未决冲突；`assumptions` 不可判定需求的责任人/到期时间；
- `evidence` 访谈/事故/校准/审查纪要/利益冲突声明。
签发条件：`N_core` 覆盖全部强制需求、`H^hard` 零违反、同意有效且未撤回、否决未触发、`δ_n<Θ_n`、`ρ_ne≥ρ_min`、审查独立且记录可核验。

### IP-127 NEL（Needs Evidence Ledger）

```python
def build_needs_ledger(sources, stakeholders):
    N = []
    for src in sources:                    # 访谈/观察/事故/工单/遥测
        for raw in src.items:
            n = Need(
                stakeholder=attribute(raw, stakeholders),
                type=classify_need(raw),
                statement=raw.text,
                evidence=trace(raw),
                negative=is_negative(raw),
                residual=operationalize(raw),
                threshold=elicit_threshold(raw),
                mandatory=is_mandatory(raw, stakeholders),
            )
            N.append(n)
    N = reconcile_conflicts(N, stakeholders)   # 冲突保留，不强行平均
    assert traceability_complete(N)            # 无孤儿能力/孤儿需求
    return N

def prune_orphan_capabilities(capabilities, N):
    return {c for c in capabilities if any(c in path(n) for n in N)}
```

### IP-128 NDD（Need Decidability & Drift）

```python
def decidability_audit(n, obs_space, budget):
    r = operationalize(n)
    if r is None:
        return Dec(False, reason='not_observable')
    cal = calibrate(r)
    power = power_analysis(r, n.threshold, budget)
    return Dec(cal.bound <= eps_r and power >= 1 - beta,
               reason='ok' if cal.bound <= eps_r else 'miscalibrated')

def next_probe(N, budget):
    undecided = [n for n in N if not n.decidable]
    return max(undecided, key=lambda n: value_of_information(n) / cost(n),
               default=None)

def drift_monitor(N, telemetry, context):
    triggers = []
    for n in N:
        if n.residual is None:
            continue
        d = abs(estimate(n.residual, telemetry) - n.baseline)
        if d > n.delta or context_changed(n, context) or consent_changed(n):
            triggers.append((n, d, 'drift_or_context'))
    return triggers
```

### IP-129 SRL（Stakeholder Risk Ledger）

```python
def stakeholder_risk_ledger(scenario, policy, S, hard_limits):
    ledger = []
    for s in S:
        h = harm_profile(policy, s)        # 物理/隐私/自主/公平/尊严/欺骗
        c = consent_state(s, used_data(policy), policy.actions)
        v = veto_status(s, scenario, policy)
        ledger.append(StakeholderEntry(
            s, h, c, v, accountability=assign(s), appeal=channel(s)))
    return ledger

def ethically_admissible(ledger, hard_limits):
    for e in ledger:
        if e.veto:
            return False, 'veto', e
        if not consent_covers(e.consent, e.actions):
            return False, 'consent_invalid', e
        if any(e.h[j] > hard_limits[j] for j in HARD_DIMS):
            return False, 'hard_harm', e
    return True, 'ok', None
```

### IP-130 ERG（Ethical Runtime Gate）

```python
def ethical_gate(u_nom, x, theta, ledger, B_rev, auth):
    feasible = []
    for u in neighborhood(u_nom):
        ok, why, e = runtime_eth_check(u, x, theta, ledger)
        if not ok:
            continue
        if irreversible(u) and not authorized(u, auth, e):
            continue
        feasible.append(u)
    if not feasible:
        return ethical_stop(x), 'ethics_infeasible'   # fail-closed
    u = project_L2(feasible, u_nom)
    if irreversible(u):
        if B_rev < cost_irr(u):
            return request_human(u, evidence=e), 'authorization_required'
        B_rev -= cost_irr(u)
    audit_append(x, u, auth)
    return u, 'ok'
```

### IP-131 NEA（Need-Ethics Arbitration）

```python
def need_ethics_arbitrate(N, ledger, policies, budgets):
    # 第一层：硬伦理约束，绝对优先
    alive = []
    for p in policies:
        ok, why, e = ethically_admissible(ledger_for(p), budgets.hard)
        if ok:
            alive.append(p)
        else:
            p.reject(why, e)
    # 第二层：强制需求与负需求
    alive = [p for p in alive if cov_mandatory(p, N) == 1.0]
    alive = [p for p in alive if negative_violations(p, N) == 0]
    if not alive:
        return ('reject', 'no_policy_meets_hard_constraints')
    # 第三层：可选效用；同分时取最小残差裕度最大者
    return max(alive, key=lambda p: (min_margin(p, N), optional_utility(p)))
```

### IP-132 NEC（Need-Ethics Certificate）

```python
def need_ethics_certificate(policy, theta, N, ledger, budgets, review):
    if not review.independent or not review.coi_clean:
        return ('reject', 'review_not_independent')
    R = {n.id: residual(policy, theta, n) for n in N}
    unmet = [n for n in N if n.mandatory and not satisfied(n, R[n.id])]
    if unmet:
        return ('reject', 'mandatory_unmet', unmet)
    ok, why, e = ethically_admissible(ledger, budgets.hard)
    if not ok:
        return ('reject', why, e)
    if not consent_valid(ledger, policy):
        return ('reject', 'consent_invalid')
    triggers = drift_monitor(N, theta.telemetry, theta.context)
    if triggers:
        return ('reject', 'need_drift', triggers)
    rho_ne = worst_case_acceptance(policy, N, ledger, theta.eps)
    if rho_ne < budgets.rho_min:
        return ('reject', 'need_ethics_robustness_fail')
    return ('ok', NEC(N_core(N), R, ledger, audit_log(), drift(N), rho_ne,
                      dissent(N), assumptions(N), evidence(N)))
```

## 3. 复杂度与正确性

| 组件 | 时间复杂度 | 空间复杂度 | 正确性关键 |
|---|---|---|---|
| NEL | O(|E|·|N| + |N|²) | O(|N|·|R|) | 主体覆盖、证据可追溯、冲突不平均化 |
| NDD | O(|N|·(T_obs+C_cal)) | O(|N|) | 可观测性、校准界、漂移可检 |
| SRL | O(|S|·|H|·T_policy) | O(|S|·|H|) | 台账完整、同意状态机、否决权 |
| ERG | O(|U|·|H|)/步 | O(|U|) | fail-closed、授权、审计抗篡改 |
| NEA | O(|Π|·|N| + |N|²) | O(|N|²) | 字典序、硬约束优先 |
| NEC | O(|N|+|S|+|轨迹|+N_adv·|Θ|) | O(|N|+|S|) | 审查独立、覆盖完备、漂移可检 |

**正确性定理（Need-Ethics Deployment Soundness）**
假设第 55 轮 (A29)–(A32) 成立；**(A33)** 需求台账来自分层且可审计的主体采样，强制需求由合法程序确定，少数派异议被记录；**(A34)** 每个可判定需求的残差估计满足 `|r̂-r|≤ε_r`，漂移检测延迟 ≤ `τ_n`；**(A35)** 伦理硬上界与否决权由独立、无利益冲突的审查机构设定，且不是从部署数据中学习/优化得到；**(A36)** 运行时伦理门 fail-closed，审计链抗篡改，人工授权/接管通道可用，回退 `u_eth_stop∈𝒳_safe`。

则部署后的经验安全与需求满足满足：
```
P(accept ∧ (¬physical_safe ∨ ∃n∈N_m unmet ∨ drift undetected))
  ≤ P(||Σ-Σ̂||_∞ > ε_s) + P(residual miscalibrated)
    + P(drift undetected) + P(shield/fallback fails)
```
而伦理性只能给出 **条件性** 结论：
```
P(accept ∧ hard_eth_violation | E_complete ∧ review_independent) = 0
P(accept ∧ hard_eth_violation) ≤ P(E_incomplete) + P(review compromised)
```
其中 `P(E_incomplete)` **不可由部署数据估计**：它只能靠独立审查、利益冲突披露、少数派异议、申诉与撤销程序来降低。因此证书绝不能声称“无条件零伦理违反”，也不允许把伦理项折成概率/加权项后与任务效用交换。

## 4. 实验设计 E167–E171

| 实验 | 指标 | 目标 |
|---|---|---|
| E167 需求台账覆盖 | 强制需求可追溯率、可判定率、评分者一致性 κ、孤儿能力数 | 100% / ≥85% / ≥0.80 / 0 |
| E168 隐性需求与负需求发现 | 相比“仅访谈”的新增隐性需求、误报率、负需求捕获率 | +30% / ≤10% / ≥90% |
| E169 伦理台账与运行时门 | 红队场景硬违反数、误阻断率、授权延迟 P95 | 0（审计集）/ ≤5% / ≤200ms |
| E170 冲突仲裁与退出权 | 与独立伦理委员会一致率、申诉率、撤回同意后功能降级成功率 | ≥90% / ≤5% / 100% |
| E171 长期漂移与撤销传播 | 漂移检测召回、P95 延迟、同意撤回传播时间、隐私投诉增量 | ≥0.90 / ≤1 天 / ≤1 min / 不增加 |

**证伪条件**：若 E167 中强制需求可追溯率无法达到 100%，或 E169 在审计集出现任一硬违反，或 E171 中撤回同意后相关功能未在时限内降级，则本轮“需求-伦理联合证书”判定为不可部署，不得进入下一轮叠加。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|

## 6. 本轮最大风险

**一句话**：需求-伦理联合证书把“做得到”扩展为“该不该、为谁做”，但其有效性双重依赖需求台账的代表性与伦理审查的独立性；一旦只采到强势主体的声音、或伦理审查由开发方自证，证书就会把偏置与价值冲突洗成“合规”，系统会以高置信执行一个技术上正确、伦理上错误的任务——因此必须以 **分层需求证据 + 独立否决权 + 可撤销同意** 三重制度护栏，宁可判定“不可部署”，绝不把伦理审查降格为概率项或事后文档。

def need_ethics_arbitrate(N, ledger, policies, budgets):

    alive = []
    for p in policies:

        if ok:
            alive.append(p)
        else:
            p.reject(why, e)

    alive = [p for p in alive if negative_violations(p, N) == 0]
    if not alive:
        return ('reject', 'no_policy_meets_hard_constraints')
    # 第三层：可选效用；同分时取最小残差裕度最大者
    return max(alive, key=lambda p: (min_margin(p, N), optional_utility(p)))

## 3. 推导：伦理不可折现与需求覆盖下界

**推导（标量化必然允许越界）**：若把任务效用与伦理伤害合成 `J = U - λ·h`，则对任意有限 `λ>0`，总存在任务增益 `ΔU > λ·Δh`，使增加伤害在标量目标下“划算”。等价地，`∂J/∂h = -λ > -∞`，伤害永远可被有限效用交换。因此任何有限权重的惩罚项都会在某个工作点上越过硬上界。要保持否决权，必须使用 **约束/字典序**，而不是加权：
`π ≻ π' ⇔ (h(π)<h(π')) ∨ (h(π)=h(π') ∧ cov(π)>cov(π')) ∨ ...`，硬约束层不允许被后续层补偿。

**数值推演（为什么“任务成功率更高”不能救场）**：设某非同意旁观者的硬伤害上界 `H^hard=10^-4`，系统通过提速可把任务成功率从 0.80 提到 0.92。在 `J=U-λh` 下，只要 `λ<1200`，优化器就会选择提速；但在字典序门控下，该方案在第一层即被拒绝，与 `U` 提高多少无关。这正是“伦理审查”与“伦理打分”的差别。

**需求覆盖的样本下界**：若某强制需求只靠抽样验证，`n` 次独立试验零失败时，其成功率的 95% Clopper–Pearson 下界约为 `(0.05)^(1/n)`。例如 `n=30` 时下界约 `0.905`，并不到 `0.95`。因此“覆盖率 100%”必须是 **逐条强制需求的可判定验证**，不能用总体抽样成功率替代；无法逐条判定的需求必须进入 `assumptions` 并在证书中显式暴露。
