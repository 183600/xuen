### 第 1 轮灵感驱动研究记录

**灵感词**：服务设计、技能组合

**直觉与动机**：
把前几轮串起来看：KEMPC 给了「常识包容」，CADVS 给了「证书链 + 视觉伺服 + 时序熔断」，CA-VLA 给了「契约锚定的语义意图」。但这套体系一直是**以单个控制步、单个技能为单位**做认证的。真实部署不是「一步控制」，而是一段**服务旅程**：靠近 → 抓取 → 搬运 → 交接给人 → 收尾。旅程里有触点（touchpoint），更有**接缝（seam / handoff）**；而故障恰恰聚集在接缝上——这正是服务设计（service design）反复强调的：服务的失败点（fail points）往往不在单个后台工序内部，而在前后台交界、在「关键时刻（moment of truth）」的转场处。

两个灵感词各补上过去缺失的一半：

1. **服务设计 = 给证书体系补上前台视角与接缝理论**。服务蓝图（service blueprint）的核心是「可见线（line of visibility）」：顾客只看见前台（行为是否可读、可预期、可打断），看不见后台（证书聚合、MPC 求解、KC 规则）。过去的证书几乎全是**后台正确性证书**，却没有任何东西保证「人能在关键时刻看懂并及时介入」。服务设计说：价值（含安全）是**共同生产（co-production）**的——人也是安全回路的一环。前台不可读，人就无法共同生产安全；后台再正确，有效安全也被前台截断。

2. **技能组合 = 给证书体系补上组合代数与接缝风险**。机器人能力是一组可复用技能，服务是把技能编排成旅程。但**已认证的技能不会自动组合成已认证的服务**（compositional gap）：每个技能单独过证书，接缝处却可能产生任何单技能都未认证过的联合状态。必须显式定义组合算子 ⊗、可组合关系 ⋈、接缝证书与接缝风险预算。

3. **二者闭环**：技能组合回答「后台怎么把已认证零件拼成服务」，服务设计回答「前台怎么让人看懂并共同生产」；接缝（关键时刻）是二者共同的应力集中点，也是监控预算应当倾斜的地方。

一个反直觉的洞见：**最危险的不是某个技能失败，而是一次「成功的接缝」**——每个技能都过了自己的证书，交接却制造出一个谁都没认证过的状态；服务蓝图全绿，而「服务缺口」正好落在人正盯着看的关键时刻。**整体证书不等于部分证书之和，缺口恰恰在可见线上。**

**形式化目标（增量）**：
1. 定义已认证技能 κ = (s, Pre, Post, Inv, C, β, H)：技能、入口/出口集、全程不变式、证书束、风险预算、时域；健全性 Sound(κ) 以「不变式或证书在 H 内被违反的概率 ≤ β」刻画。
2. 定义组合算子 ⊗ 与可组合关系 ⋈：接口非空、出口满足下一入口不变式、证书时序连续、无资源冲突；并强制接缝风险 β_seam 只能由证据估计，无证据即拒绝认证。
3. 构造接缝超加性：证明存在 Post₁ ⊄ Pre₂ 的技能对，使 β_seam 不被 β₁+β₂ 界住（可达任意接近 1）。
4. 定义服务蓝图 B = (𝒯, Seams, L_vis, F, R, C_front, C_back) 与服务健全性 sound(B)。
5. 定义前台可读性证书 LC =（可预期、响应、可解释、可打断）与共同生产耦合 S_eff ≥ 1 − B·(1 − ρ(LC))，其中 B 为后台总违规预算、ρ(LC) 为及时介入概率。
6. 定义服务补救契约 SRC = (RTO, RPO, 补救证书, 补救完备性)：补救动作本身必须 ∈ Exec_CADVS 且前台可读。
7. 定义关键时刻监控 MoTM：按接缝风险梯度分配监控预算，而非均匀撒在全程。
8. 实验假设：接缝证书使接缝违规率较「仅组件证书」降低 ≥ 50%；MoTM 在相同监控预算下将接缝漏检率降低 ≥ 40%；可读性提升使人工及时介入率提升 ≥ 30%，S_eff 逼近 S_back。

**关键洞见**：技能组合回答「后台如何把已认证零件拼成服务」，服务设计回答「前台如何让人看懂并共同生产安全」；接缝（关键时刻）是二者共同的应力集中点。真正的服务安全 = 后台健全 ∧ 前台可读 ∧ 补救完备 ∧ 接缝受控——缺一不可，且**组合安全无法仅由组件证书推出**，必须为接缝单独采集证据。

**本轮最大风险**：**接缝风险被系统性低估（接缝超加性 + 可见线遮蔽）**——若把 β_seam 当作可加小量，而实际在接触丰富的交接处它是超加的（技能互相破坏对方的证书前提），那么「每个技能都过证书」会制造全绿的服务蓝图，却把真实违规藏在人正注视的关键时刻，形成比单点失败更隐蔽的「服务级虚假安全感」。

## 2. 关键算法骨架

### IP-484 Certified Skill Object (CSO)

```python
@dataclass(frozen=True)
class CertifiedSkill:
    """已认证技能：证书随技能走，组合代数据此做类型检查。"""
    sid: str
    policy: SkillPolicy            # 复用 CADVS / SFL 的已认证子控制器
    pre: StatePredicate            # 入口集 Pre
    post: StatePredicate           # 出口集 Post
    inv: StatePredicate            # 全程不变式 Inv
    certs: frozenset[str]          # 证书束 C：{'FQC','DLC','TCVM','MRCC','KC','STL'}
    beta: float                    # 风险预算 β（违规概率上界）
    horizon: float                 # 时域 H（秒）

    def sound_bound(self) -> float:
        return self.beta

    def resources(self) -> frozenset[str]:
        """技能占用的执行器/工作空间资源，用于组合冲突检测。"""
        return self.policy.resource_footprint()
```

### IP-485 Skill Composition Algebra (SCA)

```python
@dataclass
class SeamCertificate:
    """接缝证书：可组合性的全部证据都集中在这里。"""
    seam_inv: StatePredicate            # 交接窗口内必须成立的联合不变式
    temporal_ok: bool                   # 证书在 Δt_handoff 内保持有效（TCVM）
    no_resource_conflict: bool          # 执行器/工作空间互斥
    beta_seam: float                    # 由证据估计的接缝风险，禁止默认 0
    evidence: list[SeamSample]          # MoTM 采集的接缝样本


class NotComposable(Exception):
    pass


def compose(k1: CertifiedSkill, k2: CertifiedSkill,
            seam_evidence: list[SeamSample] | None) -> CertifiedSkill:
    """组合算子 ⊗：把两个已认证技能合成一个已认证复合技能。

    核心不变量：接缝风险只能由证据估计；无证据 -> 拒绝组合，
    而不是默认把 β_seam 当作 0（这是『组合不可由组件单独认证』的算法化）。
    """
    # 1) 接口非空：Post1 ∩ Pre2 ≠ ∅
    if disjoint(k1.post, k2.pre):
        raise NotComposable('empty interface: Post1 ∩ Pre2 = ∅')

    # 2) 出口不蕴含下一入口 -> 必须有接缝证据补证，否则拒绝
    post_implies_pre = implies(k1.post, k2.pre)
    if not post_implies_pre and not seam_evidence:
        raise NotComposable('Post1 ⊄ Pre2 and no seam evidence: uncertifiable')

    # 3) 证书时序连续：出口时仍有效的证书须撑过 Δt_handoff
    seam_certs = k1.certs & k2.certs
    temporal_ok = ('TCVM' not in seam_certs) or cert_age_ok(k1, k2, DT_HANDOFF)
    if not temporal_ok:
        raise NotComposable('certificate expires across seam')

    # 4) 资源冲突：两技能不能同时争用同一执行器/工作空间
    no_conflict = k1.resources().isdisjoint(k2.resources())
    if not no_conflict:
        raise NotComposable('resource contention at seam')

    # 5) 接缝风险：必须来自证据；无证据或证据不足 -> 拒绝认证
    beta_seam = estimate_seam_risk(seam_evidence, k1.post, k2.pre) \
        if seam_evidence else float('inf')
    if not np.isfinite(beta_seam):
        raise NotComposable('insufficient seam evidence')

    seam_inv = And(k1.inv, k2.inv, seam_invariant(k1, k2))
    return CertifiedSkill(
        sid=f'({k1.sid}⊗{k2.sid})',
        policy=SequentialPolicy(k1.policy, k2.policy),
        pre=k1.pre,
        post=k2.post,
        inv=And(k1.inv, k2.inv, seam_inv),
        certs=k1.certs | k2.certs | seam_certs | {'SEAM'},
        beta=k1.beta + k2.beta + beta_seam,     # 仅当 ⋈ 成立时可加的界
        horizon=k1.horizon + k2.horizon,
    )


def estimate_seam_risk(evidence, post1, pre2) -> float:
    """从接缝证据估计 P(接缝违规)；样本不足直接返回 inf。"""
    if len(evidence) < N_SEAM_MIN:
        return float('inf')
    viol = np.array([e.violated for e in evidence], dtype=float)
    # 保守上界：Wilson 置信上界 + 分布失配修正项
    p_hat, ub = wilson_upper(viol.sum(), len(viol), delta=0.05)
    mismatch = wasserstein(empirical_exit_dist(evidence), pre2.reference_dist())
    return float(min(1.0, ub + MISMATCH_COEF * mismatch))
```

**设计要点**：`compose` 在 `Post₁ ⊄ Pre₂` 且无接缝证据时**直接拒绝**，而不是乐观地令 β_seam=0。这把「组合安全无法由组件证书推出」（见命题 36）从一句口号变成编译期不变量。

### IP-486 Service Blueprint Compiler (SBC)

```python
@dataclass
class ServiceBlueprint:
    touchpoints: list[Touchpoint]          # 有序触点（服务旅程）
    seams: list[Seam]                      # 触点间接缝（关键时刻）
    visibility: dict[str, str]             # L_vis: 'front' | 'back'
    fail_points: list[FailPoint]           # F（含接缝）
    recovery: dict[str, RecoveryAction]    # R
    front_certs: dict[str, LegibilityCertificate]
    back_certs: dict[str, frozenset[str]]


def compile_blueprint(journey: list[CertifiedSkill],
                      lc_model, motm) -> ServiceBlueprint:
    """把已认证技能序列编译成服务蓝图：前后台分层 + 故障点 + 补救映射。"""
    bps = []
    for i, k in enumerate(journey):
        bps.append(Touchpoint(id=f'tp{i}', skill=k,
                              visibility='front' if k.has_human_contact else 'back'))
    seams = []
    for i in range(len(journey) - 1):
        ev = motm.collect_seam_evidence(journey[i], journey[i+1])
        composite = compose(journey[i], journey[i+1], ev)   # 复用组合代数
        seams.append(Seam(id=f'seam{i}', cert=composite, evidence=ev))
    # 故障点 = 每个触点 + 每个接缝；补救映射复用 SFL，但须通过 SRC 认证
    fail_points = [FailPoint(tp.id) for tp in bps] + [FailPoint(s.id) for s in seams]
    recovery = {f.id: default_recovery(f) for f in fail_points}
    front = {tp.id: lc_model.assess(tp) for tp in bps if tp.visibility == 'front'}
    back = {tp.id: tp.skill.certs for tp in bps}
    return ServiceBlueprint(bps, seams, {tp.id: tp.visibility for tp in bps},
                            fail_points, recovery, front, back)


def service_sound(bp: ServiceBlueprint, state) -> tuple[bool, list[str]]:
    """服务级健全性：后台健全 ∧ 前台可读 ∧ 接缝受控 ∧ 补救完备。"""
    issues = []
    for tp in bp.touchpoints:
        if not certs_hold(bp.back_certs[tp.id], state):
            issues.append(f'back:{tp.id}')
        if tp.visibility == 'front' and not bp.front_certs[tp.id].valid():
            issues.append(f'front:{tp.id}')
    for seam in bp.seams:
        if seam.beta_seam_estimate > TAU_SEAM:
            issues.append(f'seam:{seam.id}')
    for f in bp.fail_points:
        r = bp.recovery[f.id]
        if not r.certified or r.success_prob < 1 - DELTA_REC:
            issues.append(f'recovery:{f.id}')
    return len(issues) == 0, issues
```

### IP-487 Legibility Certificate (LC)

```python
@dataclass
class LegibilityCertificate:
    """前台证书：人能否在关键时刻看懂并介入（服务设计的前台视角）。"""
    predictability: float      # 行为可预期（轨迹可读、意图可预测）
    responsiveness: float      # 响应时延（人发出中断 -> 系统可见响应，秒）
    explicability: float       # 可解释（触发规则/原因可呈现）
    interruptibility: float    # 可打断（急停/接管可达且安全）

    P_MIN, R_MAX, E_MIN, I_MIN = 0.7, 0.30, 0.6, 0.8

    def valid(self) -> bool:
        return (self.predictability >= self.P_MIN and
                self.responsiveness <= self.R_MAX and
                self.explicability >= self.E_MIN and
                self.interruptibility >= self.I_MIN)

    def coproduction_factor(self) -> float:
        """ρ(LC)：后台失效时，人能及时介入的概率（单调于四维）。"""
        return float(np.clip(
            self.predictability * self.explicability * self.interruptibility
            * np.exp(-self.responsiveness / 0.15),
            0.0, 1.0))
```

**要点**：LC 只度量**前台**，不允许读取后台证书值或 VLA 内部特征；它必须由独立的行为实验（人能否在 X ms 内按下接管、能否复述系统意图）校准，而非自报。

### IP-488 Moment-of-Truth Monitor (MoTM)

```python
class MomentOfTruthMonitor:
    """关键时刻监控：把监控预算按接缝风险梯度倾斜，而非均匀撒在全程。"""
    def __init__(self, budget_per_step: int, tau_seam: float = 0.02):
        self.budget = budget_per_step
        self.tau_seam = tau_seam
        self.seam_model = CalibratedRiskModel()

    def allocate(self, risk_grad: dict[str, float]) -> dict[str, int]:
        """高风险接缝分到更多采样预算；这是『关键时刻』的算法化。"""
        total = sum(max(v, 0.0) for v in risk_grad.values()) or 1.0
        return {sid: max(1, int(self.budget * max(v, 0.0) / total))
                for sid, v in risk_grad.items()}

    def on_seam(self, seam_id, exit_state, cert_ages, resource_state):
        feats = self._features(exit_state, cert_ages, resource_state)
        beta_hat = self.seam_model.predict(feats)       # 校准后的接缝风险
        if beta_hat > self.tau_seam:
            return RecoveryTrigger(seam_id, beta_hat, reason='seam_risk_high')
        return None

    def _features(self, x, ages, res):
        return np.array([
            state_dist_mismatch(x),        # 出口状态与下一入口参考分布失配
            max(ages.values(), default=0), # 证书最大年龄（TCVM）
            float(res.contention),         # 执行器争用度
            self.seam_model.recent_viol_rate(seam_id=None),
        ])
```

### IP-489 Service Recovery Contract (SRC)

```python
@dataclass
class ServiceRecoveryContract:
    """补救契约：补救动作本身也必须被认证且可读，否则只是换个地方不安全。"""
    rto: float            # 恢复安全态的最长时间
    rpo: float            # 允许丢失的进度
    delta_rec: float      # 补救失败概率上界
    rec_cert: frozenset[str]

    def certified_recovery(self, fail_point, state, sensor, sfl) -> ControlOutput:
        out = sfl.fallback(fail_point.reason, state, sensor)  # 复用语义回退阶梯
        # 补救动作必须落在 CADVS 已认证执行集内
        if out.path not in EXEC_CADVS:
            return ControlOutput(np.zeros(6), path='safe_stop', certs=None)
        # 且必须在 RTO 内到达安全态、且前台可读
        if not self._within_rto(out, state) or not self._legible(out):
            return ControlOutput(np.zeros(6), path='safe_stop', certs=None)
        return out
```

### SOCSC 统一执行流（单步）

```python
def socsc_step(image, instruction, state, sensor,
               blueprint, motm, src, sfl) -> ControlOutput:
    """服务导向：后台组合证书 + 前台可读性 + 接缝监控 + 认证补救。"""
    tp = blueprint.current_touchpoint(state)

    # 1) 接缝是关键时刻：密集检查接缝风险
    if blueprint.is_seam(state):
        trig = motm.on_seam(tp.seam_id, state,
                            cert_ages(state), resources(state))
        if trig is not None:
            return src.certified_recovery(trig, state, sensor, sfl)

    # 2) 执行当前已认证技能（仍走 cadvs_step 的证书链）
    out = cadvs_step(state, sensor)

    # 3) 前台可读性：不可读则衰减动作/放大意图提示（不影响后台安全性）
    if tp.visibility == 'front':
        lc = blueprint.front_certs[tp.id]
        if not lc.valid():
            out = attenuate_for_legibility(out, lc)

    # 4) 服务级健全性快照（后台 ∧ 前台 ∧ 接缝 ∧ 补救）
    ok, issues = service_sound(blueprint, state)
    if not ok:
        return sfl.fallback('service_unsound', state, sensor)
    return out
```

## 4. 正确性论证（增量更新）

### 定义 35（已认证技能）

技能 κ = (s, Pre, Post, Inv, C, β, H) **健全**，记 Sound(κ)，当且仅当：对任意 x₀ ∈ Pre，
1. 轨迹在 [0,H] 内以概率 ≥ 1−β 满足 Inv 且证书束 C 始终有效；
2. 在 H 时刻以概率 ≥ 1−β 落入 Post。
执行集 Exec(κ) ≜ {σ : σ 满足上述条件}。

### 定义 36（组合与可组合关系）

κ₁ ⊗ κ₂ ≜ (s₁∘s₂, Pre₁, Post₂, Inv₁ ∩ Inv₂ ∩ Inv_seam, C₁∪C₂∪C_seam, β₁+β₂+β_seam, H₁+H₂)。
可组合关系 κ₁ ⋈ κ₂ 成立，当且仅当：
1. Post₁ ∩ Pre₂ ≠ ∅（接口非空）；
2. Post₁ ⊆ Pre₂（或由接缝证据补证出口→入口的蕴含）；
3. 证书时序连续：出口时有效证书在 Δt_handoff 内仍有效（TCVM age < window）；
4. 资源互斥：resources(κ₁) ∩ resources(κ₂) = ∅。

### 引理 35（接缝超加性构造）

**陈述**：存在技能对 κ₁、κ₂，各自在其定义域内健全（β₁=β₂=0），但其接缝风险 β_seam 不被 β₁+β₂ 界住，可任意接近 1。

**构造与证明**：取 κ₁ =「伸向杯子」，其 Post₁ 仅保证「末端速度 ‖v_ee‖ ≤ v₀」，**不保证杯子相对夹爪静止**；取 κ₂ =「抓取」，其 Pre₂ =「物体相对夹爪静止」。在湿滑桌面上，κ₁ 的出口状态可满足 Post₁（末端速度低）但杯子仍在微滑（加速度非零），故该状态 ∈ Post₁ \ Pre₂。此时 κ₂ 在其 Pre₂ 外运行，其健全性保证不适用，抓取可失败；而 κ₁ 的证书在出口处完全成立。由于失败状态落在两技能证书都未覆盖的接缝区，β_seam 不受 β₁+β₂ 约束，可在滑移极端时趋近 1。∎

**工程含义**：`compose` 必须检查 Post₁ ⊆ Pre₂；若只满足接口非空，则必须用接缝证据显式估计 β_seam，绝不能默认可加。

### 引理 36（组合健全性的条件可加界）

**陈述**：若 κ₁ ⋈ κ₂ 成立（含 Post₁ ⊆ Pre₂ 或接缝证据），且 Sound(κ₁)、Sound(κ₂) 成立、接缝风险为 β_seam，则 Sound(κ₁ ⊗ κ₂) 成立且总违规概率 ≤ β₁ + β₂ + β_seam。

**证明**：复合轨迹唯一可能的违规来源为三个互斥事件之并：(E₁) κ₁ 阶段违反 Inv₁/C₁；(E₂) κ₂ 阶段违反 Inv₂/C₂；(E₃) 交接窗口违反 Inv_seam。因 x_{T₁} ∈ Post₁ ⊆ Pre₂，κ₂ 的健全性在交接后适用，故 E₂ 概率 ≤ β₂；E₁ ≤ β₁；E₃ ≤ β_seam（由证据估计）。对三事件取并集上界即得 β₁+β₂+β_seam。∎

**诚实声明**：该界仅在 ⋈ 成立时可加；若 Post₁ ⊄ Pre₂ 且接缝证据不足，`compose` 拒绝认证——这不是保守，而是引理 35 的直接后果。

### 命题 36（组合安全不可由组件证书单独认证）

**陈述**：仅知组件证书 C₁、C₂（即使已知精确的 β₁、β₂），无法确定组合的违规概率；存在两个接缝环境，其组件证书值完全相同而组合违规概率不同。

**证明**：组合违规概率依赖交接处的联合分布 P(x_{T₁}, x_{T₁+Δt})，即出口状态到下一入口的转移核；而 C₁、C₂ 只约束各自的边缘分布与不变式，不约束该转移核。构造两个环境，组件边缘统计相同但转移核一个平滑、一个在 Post₁\Pre₂ 处集中，则前者组合违规≈0、后者≈1，而 C₁、C₂ 完全相同。故任何仅由组件证书推出的组合认证都不健全。∎

**工程含义**：这是「已认证组件不会自动组合」的形式化版本，也是 MoTM/接缝证据**不可省略**的根本原因。

### 定义 37（服务健全性）

服务蓝图 B 在状态 x 处**健全**，记 sound(B,x)，当且仅当：
1. ∀ t ∈ 𝒯，后台证书束 C_back(t) 在 x 处成立；
2. ∀ t ∈ 𝒯 且 L_vis(t)=front，前台证书 LC_t 有效；
3. ∀ seam ∈ Seams，接缝风险 β̂_seam ≤ τ_seam；
4. ∀ f ∈ F，补救 R(f) 已认证、成功概率 ≥ 1−δ_rec 且满足 RTO。

### 引理 37（共同生产耦合）

**陈述**：设后台总违规概率上界为 B = Σ_i β_i + Σ_seam β_seam，则有效安全概率满足
S_eff ≥ 1 − B·(1 − ρ(LC))，
其中 ρ(LC) 为后台失效时人能及时介入的概率。

**证明**：把结果分为「后台未失效」（概率 ≥ 1−B）与「后台失效」（概率 ≤ B）。前者直接安全；后者只有在人及时介入时才免于伤害，概率为 ρ(LC)。故
S_eff ≥ (1−B)·1 + B·ρ(LC) = 1 − B(1 − ρ(LC))。∎

**推论**：当 ρ(LC)=1（完全可共同生产），S_eff ≥ 1，前台可读性可补偿后台残余风险；当 ρ(LC)=0（人无法介入），S_eff ≥ 1−B，前台失效直接封顶有效安全。**后台再完美，也被人机界面截断。**

### 定理（服务级执行集收缩 + 安全下界）

**陈述**：在以下假设下：
- (A1) 每个技能 Sound(κ_i)，且相邻技能满足 ⋈ 或接缝证据充分；
- (A2) 补救动作 ∈ Exec_CADVS 且满足 SRC；
- (A3) 前台证书 LC 由独立行为实验校准（非自报）；
- (A4) MoTM 接缝风险估计 β̂_seam 为 β_seam 的保守上界。

则：
1. **执行集收缩**：Exec_SOCSC ⊆ Exec_CADVS ⊆ Exec_v29；
2. **服务安全下界**：S_eff ≥ 1 − B·(1 − ρ(LC))，B = Σ_i β_i + Σ_seam β_seam；
3. **接缝受控**：∀ seam，若 β̂_seam > τ_seam 则触发补救，补救后服务重回 sound(B)。

**证明**：
1. `socsc_step` 的每个动作要么走 `cadvs_step`（∈ Exec_CADVS），要么走 `src.certified_recovery`，而后者显式要求 `out.path ∈ EXEC_CADVS`，否则退化为 safe_stop（∈ Exec_v29）。故任意服务轨迹 ∈ Exec_CADVS ⊆ Exec_v29。
2. 由引理 36，每个复合技能 Sound 且总违规 ≤ Σβ_i + Σβ_seam = B；再由引理 37 得共同生产耦合下界。
3. 接缝超阈值即调用已认证补救；由 (A2) 补救后到达安全态且仍 ∈ Exec_CADVS，故 `service_sound` 恢复。∎

**诚实声明**：B 与 ρ(LC) 都是**经验量**，由 MoTM 与人工介入日志在线估计，不是先验常数；在分布偏移、遮挡、湿滑/接触突变时会上升。定理给的是条件保证，条件由 MoTM/LC 在运行时检验。

### 命题 37（可读性指标的 Goodhart 不可行性）

**陈述**：若把 LC 当作可优化的标量奖励，且 ρ(LC) 未经独立的行为介入实验验证，则存在策略 π′ 使 LC 最大而 ρ(LC) 仍很低（例如把解释做得漂亮但系统实际上来不及被打断）。

**证明**：LC 的四维由代理指标测得（如界面文字完整度、日志丰富度），而 ρ(LC) 依赖真实的人机反应时延与可达性；两者非同一充分统计量。令 π′ 在代理指标上拉满、在真实反应时延上不变，则 LC 最优而 ρ(LC) 不变。标准 Goodhart 论证。∎

**推论**：**绝不能**把 LC 分数直接作为策略微调的奖励；LC 只能由随机化的人机介入试验校准，否则会把系统训练成「可读性应试者」。

## 5. 实验设计（本轮新增）

### 5.1 平台与基线

- **仿真**：Isaac Sim（刚体接触）+ MuJoCo（接触丰富操作），移动底座 + 双臂。
- **真机**：双臂移动操作平台，RGB-D + 腕部相机；一名操作员作为共同生产者（可急停/接管）。
- **技能库**：reach / grasp / transport / handover / place / retreat，每个技能复用 CADVS 已认证子控制器。
- **服务旅程**：「取杯 → 放桌 → 递交给人」三段，含 2 个接缝（grasp↔transport、transport↔handover）。

### 5.2 接缝/关键时刻故障注入

| 注入类型 | 位置 | 期望防御点 |
|---|---|---|
| 杯子在接缝处微滑 | grasp→transport 接缝 | 接缝证书 + β_seam 估计 |
| 交接瞬间光照突变 | transport→handover 接缝 | MoTM 分布失配 + 补救 |
| 人突然伸手 | handover 接缝 | LC 可打断 + SRC 补救 |
| 执行器争用（双臂互锁） | 任意接缝 | ⋈ 资源互斥检查 |
| 下一技能入口参考漂移 | 接缝前 | Post₁ ⊄ Pre₂ 检测 → 拒绝组合 |

### 5.3 指标

- **SSR**（服务成功率）↑；**SVR**（接缝违规率）↓；**FSR_seam**（接缝假安全率 = 接缝证书通过但实际违规）↓；
- **RSR**（补救成功率）↑；**RTO**（实际恢复时间）↓；
- **HTI**（人工及时介入率）↑；**信任校准误差** = |人主观信任 − 实际安全| ↓；
- 控制环 P99 延迟（不劣化）。

### 5.4 预期结果（待验证）

| 方法 | SSR ↑ | SVR ↓ | FSR_seam ↓ | RSR ↑ | HTI ↑ | 信任误差 ↓ |
|---|---|---|---|---|---|---|
| 仅组件证书（CA-VLA） | 74% | 21% | 0.28 | — | — | 0.31 |
| + 接缝证书（SCA） | 81% | 10% | 0.15 | — | — | 0.27 |
| + MoTM | 84% | 6% | 0.08 | 79% | — | 0.22 |
| + SRC 补救 | 87% | 5% | 0.07 | 91% | — | 0.19 |
| **+ LC 共同生产（本方案）** | **88%** | **4%** | **0.06** | **92%** | **86%** | **0.10** |

### 5.5 消融

1. **去接缝证据**（令 β_seam 默认可加）：预期 SVR/FSR_seam 显著上升，验证引理 35 与命题 36；
2. **去 MoTM**（均匀采样）：相同预算下接缝漏检率上升，验证「关键时刻倾斜」；
3. **去 LC**（后台全绿但前台不可读）：预期 HTI 下降、S_eff 显著低于 S_back，验证引理 37；
4. **去 SRC**（直接急停而非认证补救）：预期 RTO 上升、SSR 下降；
5. **放宽 ⋈ 资源互斥**：预期双臂争用导致接缝违规上升。

## 7. 本轮最大风险（最终确认）

**一句话**：**接缝超加性与可见线遮蔽的叠加**——若把已认证技能的组合当作可加安全（β_seam 默认很小），而真实接缝在接触丰富、湿滑、争用的交接处是超加的，那么「每个技能都过证书」会生成全绿的服务蓝图，却把违规藏在人正注视的关键时刻；可见线又只让人看见前台正常、看不见后台接缝失守，于是形成比单点失败更隐蔽、更难被证伪的「服务级虚假安全感」——这是服务设计与技能组合接入证书体系后，整个 SOCSC 框架能否真正落地服务现场的生死线。
