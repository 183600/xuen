# 第 43 轮（新循环第 3 轮） · 步骤分证书（StepCert）：把多模态大模型的过程评分校准成「一步一证」的统计守卫，并用步骤分给证书飞轮做密粒度信用分配（四层架构 v8）

> 承接第 42 轮 v19（Sim-Cert-RAG 飞轮：SCV × CKB × ECR）。第 42 轮自陈最大风险是「仿真偏差累积 + 检索幻觉」导致**静默失效**。本轮两个灵感词正好从「证据类型」和「证据粒度」两个维度补刀：**多模态大模型**给出仿真与几何证书都没有的**语义证据通道**——它能看见「透明杯子、正在伸入的人手、被遮挡的门把手、语义上不可能的动作」这类仿真未建模、几何边际也未必报警的场景；**步骤分**（过程奖励 process reward / 部分分 partial credit）则把「整条轨迹一张证书」拆成「一步一张证书」，让证据粒度与故障定位粒度对齐：每步单独打分、单独设阈、单独回退，整条失败时还能给出**部分分**，把信用精确记到仿真数据 / 检索模板 / 阈值 / 模型头上。关键不是「相信大模型」，而是把它降格成**只能收紧、不能放松**的统计守卫：多模态步骤分经共形风险控制校准后，只被允许把安全集**变小**（多触发降级），永远不允许把已有 worst-case 证书的安全集**变大**。这样，大模型幻觉的最坏后果从「静默地不安全」被结构性改写成「显式地不可用」——恰好与第 42 轮最担心的失效方向相反。

## 0. 直觉与动机

**灵感 1（多模态大模型 → 一条仿真与几何都没有的「语义证据通道」）**：第 42 轮的域随机化再强，也只是在**参数空间**里扰动质量、摩擦、噪声、延迟；它无法凭空发明一个**新的语义类别**——例如「这个杯子是透明的」「一只人手正从视野边缘伸进来」「门把手被布料遮住了」「这个人下一步会突然横穿」。几何证书回答的是「会不会撞上约束面」，对这些**语义层面的不可能/不安全**基本失明；而多模态大模型（视频/关键帧 + 本体感觉 + 力矩/触觉 + 语言指令 + 证书上下文）恰好擅长给出「这一步看起来是否合理、是否忠实执行、是否出现未建模实体」的过程判断。但它的判断是启发式的、会自信地错，因此本轮只把它当**统计证据**，绝不当 worst-case 证明。它要补的是 v19 的「仿真覆盖不到的语义长尾」，而不是替代几何证书。

**灵感 2（步骤分 → 一步一证 + 过程奖励 + 部分分）**：第 42 轮的证书是**整条轨迹一张**：要么过、要么不过，失败时很难回答「是哪一步、哪个证据源、哪张检索模板的错」。「步骤分」的直觉来自数学评分与过程奖励模型（PRM）：不应只奖励最终答案，而应对**中间步骤**逐步打分。落到机器人上：用接触/动力学变点把轨迹切成与 CAR 转移边对齐的语义步骤，对每一步出一张**步骤证书** `Cert_k = (m_lo,k, θ_k, p_hi,k, p_max,k, prov_k)`。这带来四个直接收益：a) **密粒度信用分配**——违约时定位到步，再用反事实重放把责任分给仿真覆盖 / 检索模板 / 阈值 / 模型；b) **部分再认证**——只对失败步及其后继重跑 CEGAR/采样，已验证前缀直接复用，成本 ∝ 失败步后缀长度；c) **步骤级课程**——步骤分作为 dense reward，采样优先高权重且可修复的步骤；d) **检索幻觉的逐步审计**——检索到的模板不再「整体相似即合并」，而是逐步骤核对忠实度，任何一步不忠实就拒绝合并。注意「部分分」只用于进度、课程与修复排序，**不能兑换安全**：关键步骤失败即整条失败。

**灵感 3（耦合 → 单边收紧定律，把「静默不安全」翻转成「显式不可用」）**：设第 42/41 轮已有的 worst-case 可部署集 `H = {x : m_lo(x) ≥ θ(x)}`（几何/时序/能量），多模态步骤分经共形校准后给出统计守卫 `G = {x : p_hi(x) ≤ p_max}`。本轮规定可部署集为 `A = H ∩ G`，于是恒有 `A ⊆ H`：**任何学习信号（包括会幻觉的多模态大模型）只能删状态、不能加状态**。这意味着大模型的错误最多造成**误触发/可用性下降**（可观测、可度量、可回退），而不会破坏已有 worst-case 保证。但必须把话说死：对**全新的语义不变式**，`G` 是唯一的证据，它只提供「在可交换性下、置信 1−α 的统计保证」，不是 worst-case；把 `G` 当作安全证明使用是**类别错误**。本轮的诚实价值是：在不污染 worst-case 安全的前提下，把第 42 轮「仿真/检索错误 → 静默不安全」改写成「有界统计语义风险 + 显式降级 + 可归因修复」。

**耦合升级**：多模态大模型提供「语义证据」，步骤分提供「证据的粒度与信用分配」，共形校准提供「从启发式分数到有限样本保证的桥」，第 42 轮的 SCV/CKB/ECR 提供「仿真、知识、边缘执行」。飞轮由此升级为 **步骤切分 → 多模态逐步打分 → 共形校准 → 步骤证书门控 → 步骤级归因 → 定向补仿真/拉黑模板/重标定 → 再校准** 的 v8 循环。

## 1. 形式化定义（增量：定义 38–45）

**定义 38（多模态步骤切分与自动机对齐）**：轨迹 `ξ = (o^vis_{1:T}, o^prop_{1:T}, o^force_{1:T}, a_{1:T}, u)`。步骤切分算子 `Π = seg(ξ) = {(τ_k, s_k, e_k)}_{k=1}^{K}`，其中 `τ_k` 为技能/接触相位标签，`[s_k, e_k]` 为时间区间，且 `{s_k,e_k}` 构成 `[1,T]` 的划分。要求**硬先验 + 软标签**：边界由接触/力矩/速度的变点检测器给出（防止大模型凭空编造边界），大模型只负责给候选段贴语义标签并映射到 CAR 边 `α: Π → E_H`。定义切分一致性误差 `ε_seg = P(α(τ_k) ≠ e_k^true)`。**约定**：任何不能对齐到某条 CAR 边、或跨越边界的段，标为 `τ=∅`，其步骤证书强制弃权。

**定义 39（多模态步骤分与过程风险）**：步骤分模型 `S_θ: (ξ, k) → [0,1] ∪ {⊥}`，输入该步的多模态证据、指令与证书上下文，输出「语义安全且忠实执行」的过程分；`⊥` 表示弃权。原始步骤风险 `r_k = 1 − S_θ(ξ,k)`。将其分解为 `r_k = r_k^sem + r_k^exe`（语义 OOD 风险 + 执行偏离风险），两者都**只是启发式信号**。步骤分即过程奖励：轨迹级回报 `R(ξ) = Σ_k w_k·S_θ(ξ,k)`，`w_k ≥ 0` 为该步关键度权重（由 CAR 边的安全影响给出）。

**定义 40（共形步骤风险校准）**：校准集 `D_cal = {(ξ_i, k_i, y_i)}`，`y_i ∈ {0,1}` 为人工/高保真仿真复核的「该步是否违反语义安全契约」。取非一致性分数 `A_i = a(S_θ(ξ_i,k_i), y_i)`，得校准分位数 `q̂_{1−α}`，对测试步输出风险上界 `p_hi,k`，使在**可交换性**下 `P(r_new ≤ p_hi,k) ≥ 1−α`。更强的轨迹级控制在「期望意义」上给保证：用共形风险控制（CRC）选阈值 `λ̂`，使 `E[Σ_k w_k·1(r_k > λ̂)] ≤ α`。为缓解轨迹内时间相关，采用按任务/本体/场景分箱的 **Mondrian 共形**。分布偏移下用**加权共形**：密度比 `π(x) = p_real(x)/p_cal(x)` 由第 42 轮漂移监控与仿真直方图估计，权重 `∝ π`，有效样本量 `ESS = (Σπ)²/Σπ²`；当 `ESS < N_min` 或 `π` 无界时，校准判定失效，输出置为最保守（`p_hi = 1` 或 `⊥`）。

**定义 41（步骤证书与单边收紧定律）**：步骤证书 `Cert_k = (m_lo,k, θ_k, p_hi,k, p_max,k, τ_k, prov_k)`，其中 `m_lo,k` 来自 v19 的 L0/几何证书（worst-case 下界），`p_hi,k` 来自定义 40（统计上界）。**关键步骤可部署条件**：`m_lo,k ≥ θ_k ∧ p_hi,k ≤ p_max,k`；非关键步骤允许 `⊥` 并进入降级。**单边收紧定律**：对任意步骤分模型 `S_θ`，`A(S_θ) = {x : m_lo(x) ≥ θ(x) ∧ p_hi^{S_θ}(x) ≤ p_max} ⊆ A(⊥) = {x : m_lo(x) ≥ θ(x)}`。故 `S_θ` 的任何错误都不会扩大 worst-case 可部署集，只影响可用性。轨迹级 `A_traj = ∩_k A_k`；关键步骤失败即整条失败，**禁止用其他步骤的高分抵消**（部分分不能兑换安全）。

**定义 42（步骤级信用分配与部分再认证）**：违约事件 `e` 落在步骤 `k*`。归因向量 `a = (a_sim, a_ret, a_thr, a_mod) ∈ Δ^3`，由步骤级反事实重放近似：分别替换仿真参数覆盖、检索模板、阈值与步骤分模型，测量违约概率的边际下降（Shapley 近似）。更新规则：`a_sim` 大 → SCV 扩展 `Δ` 重采样该步边界；`a_ret` 大 → 在 KB 中拉黑该模板的对应步骤；`a_thr` 大 → 对该分箱重标定；`a_mod` 大 → 该步进入再训练/人工复核。**部分再认证算子** `PA(C, k*)`：只对 `k*` 及其后继重跑 CEGAR/采样，前缀复用已验证步骤证书，成本 `∝ |suffix(k*)|`。**命题**：若前缀证书在漂移监控未触发时仍有效，则 `PA` 与全量再认证等价（sound）；漂移触发则必须全量重认证。

**定义 43（检索模板的步骤级忠实度审计）**：检索返回模板 `C_i`（绑定示范轨迹与逐步 pre/post 声明）。多模态大模型逐步审计，得忠实度原始分 `φ_k = audit(ξ_k, claim_k)`，经定义 40 的共形下界得 `φ_lo,k`。模板可合并当且仅当 `min_k φ_lo,k ≥ φ_min`；否则把不忠实的步骤写入 KB 的**负记录**并在检索重排中降权。这把 v19 的「整体相似即合并」改为「**逐步忠实才合并**」，直接切断检索幻觉的传播路径。

**定义 44（步骤级课程与部分分调度）**：课程难度 `D(ξ) = Σ_k w_k·max(0, 1 − S_θ(ξ,k)/c_k)`。部分分 `PC(ξ) = Σ_k w_k·1[Cert_k pass] / Σ_k w_k`。采样与修复排序优先「高 `Σ w_k(1−S_k)` 且可修复」的步骤。**类型隔离**：`PC` 只用于课程进度、修复排序与汇报，绝不作为部署放行凭据。

**定义 45（漂移感知的校准生命周期）**：定义校准有效域 `V_cal = {x : π(x) ≤ π_max ∧ ESS ≥ N_min ∧ S_t ≤ τ_drift}`（`S_t` 为第 42 轮分布偏移统计量）。进入/离开 `V_cal` 触发：离开时所有 `p_hi,k` 置最保守（或 `⊥`），关键步骤 `⊥` 触发 SafeStop/云端升级，并请求再校准与 Sim 重跑。**定理（保守退化）**：若 `⊥` 一律按违约处理，则随 `V_cal` 收缩，`A(S_θ; ⊥)` 单调不增——校准失效只会让系统更保守，不会更不安全。

## 2. 产出设计（增量 IP-57/58/59 + 升级 IP-51/54/55/56/53/50/45/47）

### 2.1 IP-57 STEP-SCORE-CALIBRATOR（SSC，步骤分校准器）
1. **切分与对齐**：接触/力矩变点做硬边界，大模型只贴语义标签并映射 CAR 边；跨边界段强制 `τ=∅`、证书弃权。
2. **过程评分模型**：多模态提示 = 关键帧 + 本体感觉窗口 + 力矩/触觉 + 指令 + 证书元数据；输出步骤分、证据摘录与弃权位；用双模型集成，分歧大即 `⊥`。
3. **共形校准层**：Mondrian 分箱 + CRC 阈值 + 加权共形（密度比、ESS 门）；每场景组缓存校准表，随 `V_cal` 生命周期失效。
4. **边缘蒸馏**：把大模型步骤分蒸馏成机载小 VLM/PRM（Orin 级）或规则化 student；不确定时异步升级云端，绝不让大模型进 1kHz 控制环。

### 2.2 IP-58 STEP-CERT-RUNTIME（SCR，步骤证书运行时）
1. **逐步门控**：`allow_k = (m_lo,k ≥ θ_k) ∧ (p_hi,k ≤ p_max,k)`；与 IP-56 的 L0 查表 / L1 INT8 监控器同栈执行。
2. **弃权语义**：`⊥` 按关键度路由——关键步 → SafeStop 或云端升级；非关键步 → 单调保守降级；EE 预算内优先“保持已验证前缀 + 只冻结故障步”。
3. **步骤证书向量上总线**：每步发布 `Cert_k`，支持**部分回滚**：已认证前缀保留，只对故障步重规划，而不是整段作废。
4. **时间预算**：大模型只在步边界/关键帧异步评估，控制环只消费最近一次**已提交**的步骤证书快照，避免把推理抖动带入实时性。

### 2.3 IP-59 STEP-ATTRIBUTION-FLYWHEEL（SAF，步骤分归因飞轮）
1. **步骤级反事实归因**：对违约步做四类重放（换仿真覆盖 / 换检索模板 / 换阈值 / 换模型），得 `(a_sim, a_ret, a_thr, a_mod)`。
2. **模板忠实度审计**：执行定义 43，产出负记录与检索降权，切断检索幻觉。
3. **部分再认证**：执行定义 42 的 `PA`，漂移触发时自动升级为全量再认证。
4. **步骤级课程与溯源**：按定义 44 调度修复顺序；每条步骤证书带 `(git_commit, sim_config_hash, calibration_hash, model_hash)`。

## 3. 四层架构 v8

```
L1: TRI-FUSE(INT8) + IP-49 LIO → 度量语义图 C_ms + 漂移界 B_t
    + 多模态证据缓冲(关键帧/本体/力触/指令) → 步骤切分硬边界(变点检测)
L2: CTC + VLM + IP-35 仲裁 → 语义步骤 Π 与 CAR 边对齐(α)；IP-57 SSC 逐步打分 + 共形校准
L3: IP-51 CAR(步骤级守卫) ← IP-56 ECR(L0查表 + L1 INT8) ← IP-58 SCR(步骤证书门控/弃权/部分回滚)
    → IP-47 逐步骤契约组合 → IP-39 规划(CBF margin=查表 m_lo) → IP-45 总线(step_cert/校准状态)
    → IP-48 认证流匹配(N*=L0 j_star) + IP-43 韵律调度 → IP-53 CMC(步骤监控器)
L4: IP-55 CKB(步骤索引 + 忠实度负记录) ← IP-54 SCV(步骤边界压力测试 + 语义 OOD + 迁移界)
    → IP-59 SAF(步骤归因 + 模板审计 + 部分再认证 + 步骤课程) → RCA 重颁步骤证书 → 契约热更新
运行期：步骤边界触发多模态打分 → 共形校准 → 步骤门控 → 违约则步骤级归因 → 定向补仿真/拉黑模板/重标定 → 再校准
```

## 4. 实验设计（E87–E95 硬门槛，承接 E79–E86）

| E88 共形覆盖率 | 步骤风险上界的经验覆盖率（i.i.d. 与按组） | ≥ 1−α（α=0.05），缺口 < 2pp |
| E89 步骤分判别力 | 不安全步 AUROC；高危漏报率（低 `p_hi` 的不安全步） | AUROC ≥ 0.9；漏报 < 1% |
| E90 检索忠实度审计 | 注入 20% 坏模板的检出率；误拒率；幻觉导致的静默失效 | 检出 ≥ 90%；误拒 ≤ 5%；静默失效 0 起 |
| E91 部分再认证 | 相对全量再认证的成本；无漂移时等价性 | 降 ≥ 5x；等价性 100% |
| E92 偏移下校准 | 加权共形覆盖率；`ESS<N_min` 时弃权率；不安全接受数 | 覆盖率缺口 < 2pp；弃权→100%；不安全接受 0 |
| E93 端到端可用性 | Nominal 占比；步骤故障后恢复时间；误触发增量 vs v19 | Nominal ≥ 80%；恢复 < 1s；误触发 ≤ +2pp |
| E94 消融 | 关闭大模型 / 未校准原始分 / 校准 / 校准+归因 | 未校准显著不安全或不稳；校准保覆盖；归因提可用性 |
| E95 步骤分对抗幻觉 | 透明/遮挡/人手入镜等对抗视频下，语义不安全步被高分的比例 | 0 步被放行（弃权或拒绝） |

回退：E88/E92 覆盖率失效 → 关闭统计语义门，回退 v19 纯 worst-case（只保留步骤切分做归因）；E89/E95 判别力不足 → 步骤分仅作建议，关键步一律人工/云端复核；E90 审计误拒过高 → 降低自动合并，退回人工确认；E91 无加速 → 关闭部分再认证，全量重认证；E93 可用性崩塌 → 放开非关键步骤的统计门，仅保关键步。

## 5. 本轮最大风险

**一句话**：步骤分证书把「安全」从纯 worst-case 悄悄扩展到了**统计语义**，而共形保证只在可交换性与支撑覆盖内成立——多模态大模型恰恰会在**没见过、最罕见**的语义场景上自信地高估，偏移一旦滑出校准支撑，`p_hi` 会虚假地小，语义漏报会再次变成静默失效；因此必须把 OOD/弃权、漂移触发的再校准与 E88/E92/E95 设为红线，且**任何情况下不得把统计语义门当作 worst-case 安全证明使用**。

### IP-57 SSC：步骤切分、过程评分与共形校准
```
def segment_and_align(xi, automaton):
    # 硬先验：接触/力矩/速度变点，避免大模型编造边界
    bounds = detect_change_points(xi.prop, xi.force, min_len=0.1)  # [(s,e)]
    segs = []
    for (s, e) in bounds:
        label = mllm_label(xi, s, e)              # 只贴语义标签
        edge = align_to_edge(label, automaton)
        if edge is None or crosses_boundary(xi, s, e):
            label, edge = EMPTY, None             # tau = 空 -> 弃权
        segs.append(Step(s, e, label, edge))
    return segs

def mllm_step_score(xi, seg, cert_ctx, template=None, ens=2):
    ev = bundle(xi.keyframes[seg], xi.prop[seg], xi.force[seg],
                xi.instruction, cert_ctx, template)
    outs = [mllm(ev, prompt=STEP_PROMPT) for _ in range(ens)]
    if disagreement([o.score for o in outs]) > TAU_DIS:
        return StepScore(s=None, evidence=None, abstain=True)
    return StepScore(s=mean(o.score for o in outs),
                     evidence=outs[0].evidence, abstain=False)

def conformal_calibrate(D_cal, alpha):
    # Mondrian：按 任务/本体/场景 分箱，避免轨迹内时间相关破坏覆盖
    calib = {}
    for g, D in group_by_scene(D_cal).items():
        A = [nonconformity(z) for z in D]          # a(S, y)
        qhat = finite_sample_quantile(A, 1 - alpha)
        lam  = crc_threshold(D, alpha)             # E[sum w_k 1(r_k > lam)] <= alpha
        calib[g] = Calibrator(qhat, lam, prov=hash(D))
    return calib

def upper_risk(z, calib, pi_hat, ess, S_t, tau_drift, pi_max):
    if S_t > tau_drift or ess < N_MIN or pi_hat(z) > pi_max:
        return 1.0                                 # 校准失效 -> 最保守
    w = pi_hat(z)                                  # 密度比 (加权共形)
    return weighted_conformal_upper(z, calib[z.group], w)
```

### IP-58 SCR：步骤证书门控与弃权路由

```
def build_step_cert(xi, seg, L0, calib, pi_hat, ess, S_t):
    m_lo, theta = L0.lookup(seg.start)             # v19 的 worst-case 下界
    sc = mllm_step_score(xi, seg, cert_ctx=L0.object())
    p_hi = 1.0 if sc.abstain else upper_risk(
        features(seg, sc), calib, pi_hat, ess, S_t, PI_MAX)
    p_max = PMAX[seg.criticality]                  # 关键度 -> 阈值
    ok_geo = (m_lo >= theta)
    ok_sem = (p_hi <= p_max)
    return StepCert(m_lo, theta, p_hi, p_max,
                    ok=(ok_geo and ok_sem),
                    abstain=sc.abstain, prov=prov_tuple())

def step_runtime_gate(cert, seg, budget):

        return PROCEED
    if cert.abstain:
        if seg.critical and budget.allow_cloud_escalation:
            return ESCALATE                        # 异步云端复核
        return SAFESTOP if seg.critical else DEGRADE
```

### IP-59 SAF：步骤归因、忠实度审计与部分再认证

```
def attribute_failure(failure, KB, SCV, thresholds):
    # 四类反事实重放：换仿真覆盖 / 换检索模板 / 换阈值 / 换模型
    a_sim = drop(failure, replace='sim_coverage')
    a_ret = drop(failure, replace='retrieved_template')
    a_thr = drop(failure, replace='threshold')
    a_mod = drop(failure, replace='step_model')
    a = normalize((a_sim, a_ret, a_thr, a_mod))
    if a[0] > thresholds.sim: SCV.expand_and_resim(failure.step)
    if a[1] > thresholds.ret: KB.blacklist_step(failure.template_id, failure.step)
    if a[2] > thresholds.thr: recalibrate(failure.group)
    if a[3] > thresholds.mod:
        KB.add_negative(failure.step); queue_human_review(failure.step)
    return a

def template_faithfulness_audit(template, xi, calib):
    phis = []
    for seg, claim in zip(segment_and_align(xi, template.H), template.step_claims):
        phi = mllm_audit(xi, seg, claim)           # 逐步忠实度原始分
        phis.append(conformal_lower(phi, calib[seg.group]))
    return min(phis)                               # 最弱一环决定合并

def partial_recertify(traj, k_star, drift, certs):
    if drift.triggered:                            # 分布已偏移 -> 必须全量
        return full_recertify(traj)
    prefix = certs[:k_star]                        # 已验证前缀直接复用
    suffix = cegar_refine(traj[k_star:], budget=BUDGET)
    return compose(prefix, suffix)                 # 成本 ∝ |suffix(k*)|
```

| 多模态大模型在罕见语义场景自信地错（OOD 幻觉） | 高 | 双模型分歧即 `⊥`；步骤嵌入 OOD 检测；E89/E95 对抗红线；关键步人在环 |
| 步骤切分错误导致证书错位 | 中-高 | 接触变点硬边界；跨界段强制 `τ=∅` 弃权；E87 门；对齐失败不产生证书 |
| 大模型延迟/成本挤压实时性 | 中-高 | 只在步边界/关键帧异步评估；边缘小 PRM 蒸馏；控制环只消费已提交快照 |
| 部分再认证误用：前缀在漂移下已失效却被复用 | 中 | 漂移监控触发即强制全量；前缀证书带版本哈希，偏移即作废 |
| 忠实度审计本身幻觉，误杀好模板 | 中 | 共形下界 + 人工抽检；误拒率入 E90 门槛；负记录可申诉回滚 |
| 部分分被当成部署放行依据 | 中 | `PC` 字段类型隔离，仅课程/汇报可用；关键步失败一律整条拒绝 |
| 步骤级阈值/权重 `w_k` 标定主观 | 中 | `w_k` 由 CAR 边安全影响 + 后果严重度导出并随证书版本化；敏感性分析入 E94 |

## 6. 本轮最大风险

**一句话**：步骤分证书把「安全」从纯 worst-case 悄悄扩展到了**统计语义**，而共形保证只在可交换性与支撑覆盖内成立——多模态大模型恰恰会在**没见过、最罕见**的语义场景上自信地高估，偏移一旦滑出校准支撑，`p_hi` 会虚假地小，语义漏报会再次变成静默失效；因此必须把 OOD/弃权、漂移触发的再校准与 E88/E92/E95 设为红线，且**任何情况下不得把统计语义门当作 worst-case 安全证明使用**。
