# 第 55 轮（承接第 54 轮 v31 GroundEdge-GenSim+++；本次灵感循环第 2 轮 / 总第 6 轮；本轮灵感：「演示数据」×「ROS」）

> 前 54 轮已建立「分布式底座 → 任务迁移证据 → 层级鲁棒性 → 动作-云边协同」的证书金字塔。本轮引入两个长期被当作"免费基础设施"的对象：**演示数据（demonstration data）** 与 **ROS（ROS 2 运行时）**。核心矛盾：**H22**：演示数据被默认当作能力真相，但它只是动作剖面的**有偏、稀疏、带噪采样**；未被演示覆盖的动作区形成"演示阴影"，上一轮的动作兼容性证书会在阴影里**虚假成立**。**H23**：ROS 2 的 QoS / 生命周期 / action 语义是证书落地的运行时契约，但证书与 QoS 之间缺少代数关系，云端签发的证书可能在边端 DDS 真实的 deadline / liveliness / durability 下**静默失效**。

## 0. 直觉与动机

**灵感 1（演示数据是动作剖面的"探针"，不是"真相"）**
直觉：把每条演示轨迹 τ 视为动作空间 A 上的一次带噪观测。上一轮的 `α_S` 是**声明占用**，演示数据给出的是**实测占用** `α̂_S`。二者之差 `Δα = |α_S − α̂_S|` 就是证书的**证据缺口**。若只信声明，就会在示教者从未触及的动作区 `A_shadow = A \ supp(α̂_S)` 里输出"零风险"假象。因此证书必须携带 `coverage` 与 `uncertainty`，而不是二值 feasible。

**灵感 2（演示者偏置是系统误差，不是噪声）**
直觉：示教者有稳定的个人动作习惯 `π_demo`，任务真实需求是 `π_task`。噪声可被更多样本平均掉，**偏置不能**。若 `TV(π_demo, π_task)` 大，演示会"过覆盖"熟练动作、"系统性遗漏"边缘动作。→ 需要**反事实演示扩展**：用局部动力学在演示状态邻域做 rollout，只在模型不确定度低的方向扩展，把阴影区从"已知可行"降级为"有界未知"，绝不升级为"已验证"。

**灵感 3（ROS 2 QoS 是鲁棒性谱的运行时投影）**
直觉：第 53 轮的鲁棒性维度 d（延迟、丢包、抖动、重启）在 ROS 2 里都有物理旋钮：`deadline` / `reliability(BEST_EFFORT↔RELIABLE)` / `durability` / `lifespan` / `liveliness`。证书里的 `τ_e`、`ρ_min(d)` 若能投影到 QoS 配置上，才是可执行承诺；否则只是纸面参数。→ 定义 **QoS 契约代数**：证书可部署 ⇔ 每条技能边存在 QoS 配置 q 使 `q ⊑ q_cert`（q 至少与证书需求一样强）。

**灵感 4（ROS 图是技能组合图的"实现镜像"）**
直觉：`G_S` 的节点=技能、边=动作兼容；ROS 图节点=lifecycle node / action server，边=topic / action 通信。组合证书要在 ROS 图"落地"，必须给出节点映射 `φ: V(G_S)→Nodes` 与边映射 `ψ: E(G_S)→Endpoints`，并检查 action 的 goal/feedback/result 时序是否满足 `c_trans ≤ τ_e`。这把抽象图与真实 DDS 图对齐，可提前发现**图级死锁/环**。

**灵感 5（演示-OS-鲁棒性三层联合证书 DJC）**
直觉：最终部署证书 = 第 54 轮 `J(ρ, A_cert, γ_ce, δ_a)` ⊕ 演示证书 `DC(prov, α̂, shadow, bias, ρ_demo^low)` ⊕ ROS 契约 `RC(φ, ψ, q_map)`。三者缺一不可：无 DC，动作剖面无证据；无 RC，证书无法执行；无 J，鲁棒性无维度谱。→ 形成"证据—契约—执行"闭环。

## 1. 形式化定义（增量：定义 121–127）

**定义 121（演示轨迹与实测动作剖面）**
演示集 `D = {τ_i}`，`τ_i = ((s_t, a_t, r_t))_{t=1..T_i}`。核加权实测剖面
```
α̂_S(a) = Σ_i Σ_t K_h(a − a_{i,t})·w_i / Σ_i Σ_t w_i
n_eff(a) = (Σ w)² / Σ w²        （有效样本量）
```

**定义 122（演示阴影与演示偏置）**
`A_shadow(ε) = { a ∈ A : n_eff(a) < n_min ∨ α̂_S(a) < ε }`。
演示偏置 `B_demo = TV(π_demo, π_task)`，其中 `π_demo` 为 D 的经验动作分布，`π_task` 来自任务规范。

**定义 123（演示数据证书 DC）**
`DC = (prov, α̂_S, A_shadow, B_demo, lic, ρ_demo^low, sig)`：
- `prov` 采集设备/场景/时钟域/操作者哈希；
- `lic` 数据授权与脱敏声明（同意范围、用途限制）；
- `ρ_demo^low(d)` 为维度 d 的鲁棒性**置信下界**（Clopper–Pearson / 自助法）；
- `sig` 签名。`DC` 可跨机构传输的只有统计量，不是原始轨迹。

**定义 124（ROS 2 QoS 契约）**
`q = (reliability, durability, deadline, lifespan, liveliness, history, depth)`。
偏序 `q ⊑ q'`（q 至少与 q' 一样强）逐分量定义：`RELIABLE` 强于 `BEST_EFFORT`、`TRANSIENT_LOCAL` 强于 `VOLATILE`、较小 `deadline` 更强、较短 `liveliness lease` 更强。

**定义 125（证书-QoS 一致性）**
联合证书 X 关于 `q_map` 可部署，记 `X ⊨_QoS q_map`，当且仅当 ∀ 边 `e=(i,j)`：
```
deadline(ψ(e)) ≤ τ_e  ∧  liveliness_lease(ψ(e)) ≤ τ_loop
∧ reliability(ψ(e)) ⊒ r_min  ∧  durability 覆盖证书声明的状态保留窗口
```
否则称该边发生 **QoS 静默失效**（配置合法、语义却不满足证书假设）。

**定义 126（演示-鲁棒性置信界）**
对维度 d：`ρ_demo^low(d) = 1 − U_d`，`U_d` 为在 `n_eff` 下失败概率的上置信界；在 `A_shadow` 上退化为区间 `[0,1]`（即不可用于签发）。

**定义 127（可部署联合证书 DJC）**
`DJC = (J, DC, RC, q_map, φ, ψ, evidence)`，`RC=(φ,ψ,q_map)`。可部署当且仅当
```
dom_J(T)=in ∧ J ⊨_QoS q_map ∧ A_shadow ∩ A_core = ∅
∧ ρ_demo^low(d) ≥ ρ_min(d)  ∀ d
```

## 2. 关键算法 伪代码

### IP-121 DPC（Demo Provenance & Coverage）

```python
def build_demo_certificate(bags, skill, A, kernel, n_min, lic):
    traces = [parse_rosbag2(b) for b in bags]   # MCAP/sqlite3: /joint_states,/tf,action goals
    prov = hash_provenance(traces)              # device/scene/clock-domain/operator
    alpha_hat, neff = kde_profile(traces, A, kernel)
    shadow = {a for a in A if neff[a] < n_min or alpha_hat[a] < EPS}
    bias = tv_distance(empirical_action_dist(traces), task_action_prior(skill))
    rho_low = beta_lower_bound(failure_counts(traces), conf=0.95)   # per dimension
    return DemoCert(prov, alpha_hat, shadow, bias, lic, rho_low)
```

### IP-122 CDE（Counterfactual Demonstration Expansion）

```python
def counterfactual_expand(demo_cert, dynamics, A_shadow, u_max, budget):
    extra = []
    for a0 in boundary(A_shadow):
        for _ in range(budget):
            traj, unc = dynamics.rollout(a0, horizon=H)   # learned local model
            if max(unc) <= u_max:                          # trust only low-uncertainty
                extra.append(traj)
    # 影区从 unknown 降为 bounded，绝不标成 verified
    return merge(demo_cert, extra, tag='counterfactual')
```

### IP-123 ROSQ（ROS QoS Contract Algebra）

```python
def qos_refines(q, need):
    return (strength(q.reliability) >= strength(need.reliability)
            and q.deadline <= need.deadline
            and q.liveliness_lease <= need.liveliness_lease
            and durability_covers(q.durability, need.state_window))

def qos_feasible(G_S, phi, psi, q_map, tau_e, rho_min):
    for (i, j) in G_S.edges:
        need = need_of(G_S[i][j], tau_e, rho_min)
        if not qos_refines(q_map[psi((i, j))], need):
            return False, ('qos_mismatch', (i, j))
    return True, 'ok'
```

### IP-124 RNC（ROS Node/Endpoint Conformance）

```python
def realize_on_ros(G_S, J, q_map):
    phi = map_skills_to_lifecycle_nodes(G_S)
    psi = map_edges_to_actions(G_S)               # goal/feedback/result
    ok, why = qos_feasible(G_S, phi, psi, q_map, J.tau_e, J.rho_min)
    if not ok: return ('reject', why)
    if cycle_or_deadlock(phi, psi): return ('reject', 'graph_cycle')
    return ('ok', RC(phi, psi, q_map))
```

### IP-125 DJC（Deployable Joint Certificate）

```python
def deployable_certificate(J, DC, G_S, q_map, tau_e, rho_min):
    RC = realize_on_ros(G_S, J, q_map)
    if RC[0] != 'ok': return ('reject', RC)
    if set(DC.shadow) & set(J.A_cert.A_core):
        return ('reject', 'core_in_demo_shadow')      # 核心动作不能落在阴影
    for d in J.rho:
        if DC.rho_low[d] < rho_min[d] and not in_trusted_region(d):
            return ('reject', 'demo_evidence_insufficient', d)
    return ('ok', DJC(J, DC, RC, q_map, evidence=collect()))
```

### IP-126 QMON（Runtime QoS Monitor）

```python
def runtime_qos_monitor(node, cert_qos, horizon):
    while horizon.tick():
        stats = node.get_qos_stats()   # DDS deadline misses / liveliness / drops
        if stats.deadline_miss_ratio > cert_qos.max_miss:
            return ('invalidate', explain_qos(stats))   # 触发 DJC 重签
    return ('ok', stats)
```

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性关键 |
|---|---|---|---|
| DPC | O(N·T·|A|) | O(|A|+N) | KDE 带宽校准、n_eff 门槛 |
| CDE | O(|∂A_shadow|·H·budget) | O(budget·H) | 不确定度阈值 sound |
| ROSQ | O(|E|) | O(|E|) | 偏序传递、QoS 语义固定 |
| RNC | O(|V|+|E|) | O(|V|+|E|) | φ/ψ 双射、无环 |
| DJC | O(|S|·|A|+|E|) | O(|A|+|E|) | 阴影-核心互斥、置信下界 |
| QMON | O(H·f) | O(1) | 漂移检测延迟 ≤ τ_loop |

**正确性定理（Demo-QoS-Grounded Deployability Soundness）**
承接第 53/54 轮 (A22)–(A28)，新增：**(A29)** D 对 `A_core` 满足 `n_eff ≥ n_min`；**(A30)** 反事实 rollout 在 `A_shadow` 上不确定度 `≤ u_max`；**(A31)** 部署窗口内 `q_map` 保持且 DDS 不违背 QoS 语义。
则
```
P_success ≥ min( 1 − Σ_d (1−ρ_demo^low(d)), 1 − Σ_d (1−ρ_min(d)) )
            − β_E − P(A_shadow ∩ A_core ≠ ∅) − P(QoS drift)
```
**证明思路**：部署失败事件三分——(i) 核心动作落在阴影导致覆盖虚假，由互斥条件排除；(ii) 鲁棒性维度失败，由演示置信下界与证书下界取较保守者控制；(iii) 运行时 QoS 漂移，由 QMON 在 `τ_loop` 内失效并触发回退。三者 union bound 即得。

## 4. 实验设计 E162–E166

| 实验 | 指标 | 目标 |
|---|---|---|
| E162 演示覆盖估计准确性 | `|α̂_S − α_real|`（仿真真值） | MAE ≤ 0.06 |
| E163 演示阴影检出 | AUROC / 召回 | AUROC ≥ 0.90，召回 ≥ 0.85 |
| E164 反事实扩展有效性 | 阴影区可部署率 vs 误报 | 可部署率 ↑ ≥ 15%，假阳性 ≤ 5% |
| E165 QoS 静默失效预测 | 与实测 DDS deadline miss 的 F1 | F1 ≥ 0.85 |
| E166 DJC vs 仅 J 端到端 | 部署成功率 / 回滚率 | 成功率 ↑ ≥ 10%，回滚率 ↓ ≥ 30% |

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 演示数据隐私与授权越界 | 高 | `lic` 授权证书 + 只传统计量（KDE/计数）+ 联邦聚合 + 脱敏签名 |
| 反事实 rollout 模型误差放大 | 高 | 不确定度阈值 + 仅低不确定方向扩展 + 真机小样本抽检 |
| ROS 版本/QoS 语义漂移 | 高 | 锁定 distro + QoS 规范化表 + 兼容性矩阵回归测试 |
| rosbag 时间戳/时钟域不一致 | 中 | `/clock` 对齐 + 单调性校验 + 丢弃跨域不可信段 |
| 阴影与核心动作交集非空 | 高 | 保守收缩 `A_core` + 主动示教请求（active teaching） |

## 6. 本轮最大风险

**一句话**：把演示数据当作动作剖面的充分证据，同时又默认 ROS 2 QoS 是"配置即契约"，是最危险的组合——演示的**系统偏置**会让阴影区被误签为可行，而 QoS 的**语义漂移**会让已签证书在边端静默失效；两者叠加时，失败既不进演示统计也不触发 QoS 事件，形成"双盲"误部署。故必须以 **阴影-核心互斥 + 演示置信下界 + 运行时 QoS 一致性监控** 三重护栏，宁可在阴影区拒签并主动索要示教，也绝不把"演示过"当成"证明过"。

## 3. 复杂度与正确性

| 组件 | 时间 | 空间 | 正确性保证 |
|---|---|---|---|
| DPC | O(N·T·|A|) | O(|A|+N) | KDE 带宽校准、`n_eff ≥ n_min` |
| CDE | O(|∂A_shadow|·H·budget) | O(budget·H) | 不确定度 `≤ u_max` sound |
| ROSQ | O(|E|) | O(|E|) | QoS 偏序传递、语义锁定 distro |
| RNC | O(|V|+|E|) | O(|V|+|E|) | `φ/ψ` 双射、无环、action 时序 |
| DJC | O(|S|·|A|+|E|) | O(|A|+|E|) | 阴影-核心互斥 + 双下界 |
| QMON | O(H·f) | O(1) | 失效检测延迟 ≤ `τ_loop` |

**正确性定理（Demo-QoS-Grounded Deployability Soundness）**
承接 (A22)–(A28)；新增 **(A29)** D 对 `A_core` 满足 `n_eff ≥ n_min`；**(A30)** 反事实 rollout 在阴影上不确定度 `≤ u_max`；**(A31)** 部署窗口内 `q_map` 保持且 DDS 不违背 QoS 语义。则：
```
P_success ≥ min(1 − Σ_d(1−ρ_demo^low(d)), 1 − Σ_d(1−ρ_min(d)))
            − β_E − P(A_shadow ∩ A_core ≠ ∅) − P(QoS drift)
```
关键：**演示证据下界与 QoS 契约同时成立才签发**，任一失效即回退到保守动作集合。

## 6. 本轮最大风险

**一句话**：把演示数据当作动作剖面的充分证据，同时默认 ROS 2 QoS"配置即契约"，是最危险的组合——演示的**系统偏置**让阴影区被误签为可行，QoS 的**语义漂移**让已签证书在边端静默失效；两者叠加时失败既不进演示统计、也不触发 QoS 事件，形成"双盲"误部署。故必须以 **阴影-核心互斥 + 演示置信下界 + 运行时 QoS 一致性监控** 三重护栏，宁可在阴影区拒签并主动索要示教，也绝不把"演示过"当成"证明过"。
