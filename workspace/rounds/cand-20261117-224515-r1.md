## 1. 直觉（两灵感的第一性原理）

**灵感 1 ·「比赛策略」→ 比赛不是"最大化均值"，而是"在噪声与预算下最大化出线概率"**

第一性原理：排行榜不是一个确定分数，而是一个**带抽样噪声的估计**。若每任务只做少量 Bernoulli 试验，32 任务平均分的标准差可以大到 8 pp（见 §2），足以让"真实第一"在观测上只排第三。于是三件事比"再涨 1 分"更重要：

- **(a) 排名是随机变量**：要优化 `P(rank ≤ k)` 或 `E[rank]`，不是只看 `E[score]`。
- **(b) 方差是策略变量**：若我们落后于领跑者（underdog），**增大方差反而提高胜率**（买彩票）；若我们领先（favorite），**降低方差**才是正解。同一套模型，`σ` 该调大还是调小，取决于 `Δ = μ − μ_leader` 的符号。
- **(c) 预算是真货币**：真机时段、电池、充电次数、提交次数、算力全都有限；"先测什么、后改什么"是一个**信息价值（value of information）**问题，而不是"把所有 IP 都做一遍"。

**灵感 2 ·「续航能力」→ 续航不是"跑得久"，而是"在长程中保留可恢复的余量"**

第一性原理：一个 episode 的成功率是各相位存活率的乘积 `Π(1−h_j)`；**它与相位顺序无关**，只与总风险有关。真正被"续航"改变的是三件事：

- **(a) 恢复需要储备**：失败后想重试/改抓/重新对齐，必须还有**剩余时间/电量/算力**。若预算被前段动作吃光，恢复的价值趋近 0。所以"续航"= **reserve ratio**（§2 的仿真给出阈值：至少留约 1 个动作步的余量，恢复才有意义）。
- **(b) 长程会漂移**：多端口共享后端时，热节流、延迟漂移、内存增长会让 p99 延迟在数小时后变差；官方会把"延迟波动/动作规律性"纳入可信度判断。⇒ 续航也是**部署层**的稳定性问题。
- **(c) 赛季会遗忘**：几十次提交跨数月，最大的风险不是"这轮没涨"，而是"某轮把冠军配置改坏了"。⇒ 需要 champion–challenger 与可回滚的冻结安全网。

**合成**：`比赛策略 × 续航` ⇒ 在 SAGE 能力栈外再包一层**RACER 元控制器**：

**Rank（排名后验）→ Allocate（预算/VOI 分配）→ Compete（方差与提交组合）→ Endure（恢复储备 / 热漂移 / 赛季无回归）**。

一句话：**SAGE 决定"能做多好"，RACER 决定"把多好换成多高的名次"。**

## 2. 本轮量化发现（机制校验，非真机结果）

> 数据：转录的 teaser 榜 8 模型 × 32 任务（`exp/lb_2026_11_04.json`）；仿真 `exp/racer_sim.py` → `exp/racer_results.json`。**teaser 数字是随机占位**，但"均值型排名 + 有限 Bernoulli + 32 任务"这一结构是真实的，因此下列结构性结论可迁移，任务级细节不可迁移。方差方向性中的 `σ` 指**策略跨提交的真实波动**（集成多样性/任务集中度），不是单次抽样噪声。

| 发现 | 数值 | 策略含义 |
|---|---|---|
| 每任务 1 次试验时的排名噪声 | 观测分 sd = **8.06 pp**；真实第一仅 **31.8%** 概率排第一；**68.2%** 概率出现"假冠军" | 低试验数下榜单近似抽奖；不要根据一次提交的 ±1–2 分做结论 |
| 试验数增加后的收敛 | n=8 → 46.5%；n=64 → 76.1%；n=256 → 94.9%（真实第一排第一） | 分辨力随 n 缓慢上升；需要很多试验才能"看见"真实强弱 |
| 检测 `δ` 所需真机预算（z=1.96，45 s/局，2 h 电池） | +1pp：**7204 局 / 90.1 robot-h / 45 次充电 / ≈15 天**；+2pp：1801 / 22.5 h / 3.8 天；+3pp：800 / 10 h / 1.7 天；+5pp：288 / 3.6 h / 0.6 天 | **+1pp 级别的优化在赛程内不可测**；只赌 ≥3pp（最好 ≥5pp）的结构性改动 |
| 方差方向性（vs 领跑者 29.7%） | μ=29.0%：`P(beat)` 随 σ 从 0.25→2 pp 由 **0.105→0.367**；μ=30.0%：由 **0.704→0.558** | underdog 应**放大方差**（集中赌高 upside 任务/提交）；favorite 应**压缩方差**（补短板、求稳） |
| 多提交 best-of-k | underdog 18.6%→56.0%（k=4）；favorite 81.5%→99.9% | 若聚合=max，多提交是**免费期权**；若聚合=mean/latest，规则相反 |
| 每任务试验分配（Neyman vs 均匀） | 方差仅降 **0.13%**（`p_i` 集中在 0.2–0.4） | **别过度设计分配**；把力气花在"增加总试验/配对设计"上 |
| 配对 A/B 的价值 | 会话噪声 5 pp 时，配对所需局数仅为非配对的 **1/1.85**；10 pp 时 **1/4.41** | 同一时段交替 A/B 可抵消光照/摆放/机器人状态的公共漂移 |
| 头名 vs 次名（MolmoAct2 vs WALL-OSS）的摇摆任务 | Unlock 0.34 pp、Store Racket 0.47、Store Earphones −0.62、Pack Bag 1.47、Open Pill Bottle −1.52、Pick Out Battery 2.01 | 名次由**近平分任务**决定；测量与改进优先给这些任务 |
| 续航/恢复（8 相位，总风险 12%） | 无恢复时顺序无关（even/late/early ≈0.878）；有恢复 q=0.6,r=2 时 late 0.948（+6.8 pp）；但预算仅 8.6 步时恢复增益 **0.2 pp**，预算 11 步时才 **6.82 pp** | **恢复必须有储备**；`ρ_res < 1/nominal` 时重试是空谈 |

**一句话**：**排行榜的分辨率远低于大多数队伍的优化幅度；真正的杠杆是"少做不可测的微调、多做结构性大改、用配对/调试把测量成本砍下来、并在关键相位留出恢复余量"。**

## 3. 研究问题（本轮）

- **Q6（协议鲁棒的排名决策）**：在 `n_trials`、聚合规则、N 都未知时，如何给出对协议不敏感的"该改/该交/该等"决策规则？
- **Q7（方差的方向性操作化）**：如何把"underdog 放大方差 / favorite 压缩方差"翻译成可执行的任务选择、模型集成与提交组合？
- **Q8（信息价值分配）**：如何用"不计分单任务调试"与"配对计分 run"以最少真机预算把候选策略的 `P(rank)` 置信区间缩到可决策？
- **Q9（续航的可测定义）**：如何定义并测出 episode 的 hazard / reserve、部署的延迟漂移、赛季的回归率，并把它们接入策略？
- **Q10（恢复预算与延迟整形）**：如何在 IP-03 的 chunk/延迟整形里预留恢复预算，同时不违反"延迟稳定/动作良构"的可信度要求？
- **Q11（投资组合剪枝）**：第 1 轮的 IP-01–08 中，哪些按"可测性 × 杠杆"应继续、降级或冻结？

## 4. 设计原则（S1–S6）

- **S1 排名优先于均值**：一切决策按 `P(rank≤k)` / `E[rank]` 排序；均值只作为排名的一个输入。
- **S2 方差是策略变量**：先判 favorite/underdog，再决定集成的多样性、任务集中度、提交组合；不默认"越稳越好"。
- **S3 先测量后投入**：任何改动必须先给出"可检测性"估计（`E(δ)`）；低于门槛的改动不进入真机主线。
- **S4 保留恢复预算**：时间/电量/算力都留 `ρ_res ≥ 1/nominal` 的余量；宁可早停一个注定失败的尝试，也不耗尽恢复能力。
- **S5 协议鲁棒**：不为单一假设（`n_trials`/聚合/N）做最优；用对冲组合与保守回退。
- **S6 赛季无回归**：永远保留一个冻结的安全提交；champion–challenger + 顺序检验 + 一键回滚。

## 5. 最小可提交闭环（MVP）与退化链

**MVP = RankPilot 看板（IP-09） + DebugFirst/VOI 协议（IP-10） + ReserveGuard 恢复预算（IP-13） + 冻结的 SAGE 安全基线。**

理由：前两者把"测量"变便宜（信息价值最高），第三者把"续航"变成可执行约束（直击本轮灵感），冻结基线保证任何情况下都有可交的东西。

**退化链**：

- L0 公开榜单/run 记录不可用 ⇒ 只用结构先验 + 自有测量，禁用 FieldModel。
- L1 debug 时段不可用 ⇒ 退回"配对计分 run"（同任务交替 A/B）。
- L2 聚合规则未知 ⇒ 提交"安全 + 高方差"组合，安全最后交（若 latest 计数）。
- L3 电池/热漂移未知 ⇒ 保守 reserve + 降分辨率/降专家数。
- L4 整条新链路失效 ⇒ 提交冻结的 SAGE 基线。

## 6. 预期贡献（可验收）

1. **把比赛形式化为"噪声排名下的预算分配"**：给出可复用的 RankPilot 看板（后验排名、`P(top-k)`、VOI、检测预算）。
2. **给出可检测性下限**：+1/+2/+3/+5 pp 所需的真机局数/电池/天数（本轮已用 teaser 结构算出量级），并明确"不要追 +1pp"的纪律。
3. **方差方向性与提交对冲的可操作规则**：favorite/underdog 的判定与对应的集成/提交策略；聚合规则未知时的鲁棒组合。
4. **续航的三层定义与指标**：episode hazard/reserve、部署延迟漂移、赛季回归率；并证明"恢复需要储备"的阈值。
5. **先调试后计分的协议**：用单任务 debug + 配对 A/B 把真机预算砍 1.1–4.4×（取决于会话噪声）。
6. **对第 1 轮 IP 的成本-可测性剪枝**：给出下一轮的投资组合，而不是继续平均用力。

## 7. 本轮最大风险

**一句话**：本轮所有"任务级"结论（哪些是 swing 任务、对手在哪弱）都建立在 **teaser 占位榜的随机数字**上，而真正可迁移的只有"噪声/预算/方差/储备"这些只依赖赛制结构的结论——一旦把占位数据当成真实对手分布去做精细分配，就会在真实榜单上把预算押错地方；此外评测协议（`n_trials`、聚合规则、N）本身未知，任何"最优提交顺序"都可能在官方口径下失效。

## 8. 下一轮迭代计划（深化与修剪，不推倒重来）

- **深化**：RankPilot 做成离线 dashboard（输入：公开 run 记录 + 自有 debug/scored 结果；输出：`P(top-k)` 与下一步动作）；Stamina 的 hazard 与第 1 轮六因子 `Ŝ` 对齐；ReserveGuard 接进 IP-03 的 chunk/延迟整形。
- **修剪**：IP-05（pivot）、IP-07（双空间）因"零/低成本探测后才能判断、且当前不可测"降为 P2；IP-04 的跨 episode 在线适配因合规与不可测性降为"仅 episode 内调制"。
- **纪律**：每轮只押一个 ≥3pp 的结构性改动；其余改动只做 debug 级验证，不上计分主线。

# 第 2 轮产物 · 创新点清单 v2（UniBot 线）：**UniBot-RACER**

> **RACER = Rank-Aware Competition & Endurance Router**（排名感知 · 比赛与续航路由器）。
> 定位：包在 UniBot-SAGE（第 1 轮能力栈）外面的**元控制器**；不改主干能力，只决定"测什么、改什么、交什么、留多少余量"。
> **数据纪律**：榜单数字来自 `unibot.unitree.com/leaderboard_data.json`（teaser/占位，`gen_leaderboard.py` 随机生成，2026-11-17 仍未正式发布）；本轮仿真（`exp/racer_sim.py` → `exp/racer_results.json`）只做**决策论机制校验**，不是真机结果。新增事实（评测模式、电池）来源见 §10。

## 0. 本轮结论摘要

**一句话路线**：把"比赛策略 × 续航"编译成一个**预算约束下的序贯决策层**：

`Rank（排名后验） → Allocate（VOI/预算） → Compete（方差/提交组合） → Endure（恢复储备/热漂移/赛季无回归）`。

**四条量化依据（来自本轮仿真，详见 §2）**：

| 证据 | 数值 | 推出的设计 |
|---|---|---|
| 每任务 1 次试验时，观测分 sd ≈ 8.06 pp，"假冠军"概率 68.2% | 榜单在低试验数下是抽奖 | **RankPilot（IP-09）**：按 `P(top-k)` 决策，不按单次分数 |
| 检测 +1pp 需 ≈7204 局 / 90 robot-h / 45 次充电；+5pp 只需 288 局 / 3.6 h | 微小改动的信噪比不可接受 | **可检测性门（S3）**：只赌 ≥3pp；DebugFirst（IP-10） |
| underdog 的 `P(beat)` 随 σ 从 0.105→0.367；favorite 反向 0.704→0.558 | 方差有方向性 | **PortfolioSubmit（IP-11）**：favorite 求稳、underdog 买期权 |
| 恢复 +6.8 pp，但预算仅 8.6 步时增益降到 0.2 pp | 恢复被储备门控 | **ReserveGuard（IP-13）/ Stamina（IP-12）**：留 reserve |

**合规红线（沿用 P5/P6）**：单 checkpoint、单 API；不用评测侧私有信息；不读题硬编码；不利用未声明执行语义。RACER 只做**决策与工程**，不改变"一个模型服务"的合规形态。

| **IP-12** | Stamina 相位风险与恢复 | P1 | 用 hazard 模型定位"哪一相位最危险"，用恢复算子换成功率 | 第 1 轮六因子 | hazard 估计校准；恢复增益 ≥5 pp（有储备时） |
| **IP-13** | ReserveGuard 恢复预算器 | P1 | 恢复/重抓/重对齐必须从预算里预扣；储备不足则早停回安全 | IP-03/IP-12 | 超时率下降；有储备时段成功率不降 |
| **IP-14** | ThermoGuard 延迟/热漂移控制 | P1 | 用反馈控制把 p99 延迟钉在预算内，主动降算力而非被动节流 | IP-03/IP-08 | 8 h p99 漂移 ≤10%；降级 <0.5% |
| **IP-15** | SeasonVault 赛季无回归 | P1 | champion–challenger + 顺序检验 + 冻结安全网 + 一键回滚 | 版本管理 | 赛季回归率 ≤2%；误接受率受控 |
| **IP-16** | FieldModel 对手/场地建模 | P2 | 只在公开 run 记录可用时估对手任务级强弱；teaser 仅用于管道校验 | Runs 页 | 对手预测校准；仅作先验，不单独决策 |

> **P0 = 本轮 MVP**；**P1 = 机制正确、但需先拿到协议/压测数据**；**P2 = 条件推进**。第 1 轮 IP-01–IP-08 保留，投资组合见 §9。

## 2. 创新点详述

### IP-09 · RankPilot（P0）

- **动机**：榜单是 32 个 Bernoulli 的均值估计，低 n 下 sd 可达 8 pp（§2-A），单次分数不可用于决策；而"该不该改、该不该交"本质是**排序决策**。
- **与现有做法的差异**：别人看"平均成功率 +X 分"；我们维护每个候选策略与每个对手的后验 `(μ, σ)`，输出 `P(rank≤k)` 与"下一步动作"（measure / improve / submit / hold），并把检测预算 `E(δ)` 作为门。
- **技术可行性**：高（统计 + 看板）。输入：公开 run 记录（一旦发布）、自有 debug/scored 结果、teaser 结构先验（仅作弱先验）。输出：后验、置信区间、动作建议。
- **落地步骤**：①定义数据 schema（run/task/arm/n/policy/version）；②Beta-Binomial 或正态近似后验；③对手建模（层级先验，teaser 权重→0）；④`P(top-k)` 与 `E[rank]` 蒙特卡洛；⑤VOI：下一步最值得测的任务/策略；⑥预注册决策规则，避免事后改口径。
- **风险**：①对手数据不可得 ⇒ 退化为"只估自己"的置信区间；②把 teaser 当真 ⇒ 强制 teaser 权重为 0，只保留结构；③过度建模 ⇒ 先做简单 Beta-Binomial，按 E621 判断是否值得复杂化。

### IP-10 · DebugFirst（P0）

- **动机**：官网明确有"不计分单任务调试"通道（0 排行榜风险），而计分 run 覆盖 32 任务、机会稀缺；若把 debug 当"小计分"，就能用极低成本测机制。
- **与现有做法的差异**：常见做法是"改完直接约计分时段"；我们把它变成**序贯实验设计**：debug 先估计方向与量级 → 计算 `E(δ)` → 只有"在可承受预算内可检测"的改动才进计分。
- **技术可行性**：高。关键是把 debug 结果**只用于机制符号/量级**，不用于排行榜校准（debug 的泛化场景覆盖未知）。
- **落地步骤**：①选 3–5 个"机制最该起作用"的任务做 debug；②每个候选策略在 debug 任务上做配对 A/B（同一时段交替）；③用 Beta 后验给出 `P(p_B>p_A)` 与效应区间；④若区间跨 0 或效应 < `δ_min`，不约计分；⑤记录"debug→计分"的相关性，作为方法自证。
- **风险**：①debug 与计分分布不一致 ⇒ 只用符号/量级，不迁移绝对值；②debug 时段也有限 ⇒ 只测最不确定且最影响决策的任务（VOI 排序）；③配对需要控制顺序/疲劳 ⇒ 随机化 A/B 顺序。

### IP-11 · PortfolioSubmit（P0）

- **动机**：聚合规则未知（max/latest/mean），而方差方向性意味着"最优方差"取决于我们相对领跑者的位置（§2-B）。单一提交无法同时覆盖两种世界。
- **与现有做法的差异**：别人只交"当前最强"；我们交一个**组合**：一个 μ-max 安全候选 + 一个 σ-max 高方差候选（不同集成/不同任务集中度/不同 chunk 配置），并按聚合规则决定顺序。
- **技术可行性**：中–高。需要多个候选共享同一主干的不同配置（仍单 checkpoint 可覆盖，或按"一次一个提交"的规则分次交）。
- **落地步骤**：①定义候选生成器（安全=单专家+保守 chunk；高方差=多专家+激进 chunk/更强探索）；②估计每个候选的 `(μ, σ)`；③按 `A` 的三种假设分别算 `P(top-k)` 与 regret；④若 `A=latest`，安全候选最后交；若 `A=max`，先交高方差；⑤合规检查：确认"多次提交"是否允许不同配置、是否共享 token 规则。
- **风险**：①聚合规则若为 mean，高方差候选会拖低均值 ⇒ 默认只把高方差候选放在"若 max 才计数"的位置；②多次提交可能触发审核 ⇒ 先读规则；③候选间相关 ⇒ 用"有效独立数"折算 `k_eff`，不盲目乘以 k。

### IP-12 · Stamina（P1）

- **动机**：`P(success)=Π(1−h_j)` 与相位顺序无关（§2 仿真），所以"断点在最后一环"的正确解读是"插入/对齐相位的 hazard 最高"，不是"晚发生所以更糟"。要降低总 hazard，必须定位**最危险相位**并配恢复。
- **与现有做法的差异**：第 1 轮 IP-02 只做抓握确认；Stamina 把"相位 hazard + 恢复算子"显式化，并与六因子对齐。
- **技术可行性**：中。hazard 标签可从官方数据用规则 + VLM 伪标；恢复算子先用规则/检索动作，再考虑学习。
- **落地步骤**：①用第 1 轮六因子标签估计每任务每相位的 `h_j`；②识别 top-hazard 相位；③训练/规则化恢复算子（重抓、重对齐、退回安全位）；④用数据估计恢复成功率 `q` 与代价 `c`；⑤只在"有储备"时启用（交给 IP-13）。
- **风险**：①hazard 标签噪声 ⇒ 多标注器一致性；②恢复引入新失败模式 ⇒ 上限次数 + 禁区；③恢复若不能在预算内完成 ⇒ 见 IP-13。

### IP-13 · ReserveGuard（P1）

- **动机**：§2 仿真显示，恢复的收益被**储备比**门控：预算 8.6 步（ρ=0.075）时恢复增益 0.2 pp，预算 11 步（ρ=0.375）时 6.82 pp。没有储备，重试只是浪费。
- **与现有做法的差异**：第 1 轮只设"最大重抓 3 次"；ReserveGuard 把"剩余预算"作为一等约束：恢复前先算"是否付得起"，付不起就早停回安全。
- **技术可行性**：高（工程 + 简单规则）。难点是剩余预算/电量的可靠估计。
- **落地步骤**：①在线估计剩余时间/步数/电量（保守下界）；②定义 nominal 成本与 reserve 比；③恢复动作预扣成本，超预算则放弃并回安全；④与 IP-03 chunk 调度联动（抓握/对齐相位用短 chunk，保留细粒度恢复机会）；⑤审计导出"早停/降级"计数。
- **风险**：①早停会放弃本可救回的局 ⇒ 只在"注定失败"的高置信下早停；②电量估计误差 ⇒ 用保守下界；③与官方超时语义不符 ⇒ 先用 client 复刻实测。

### IP-14 · ThermoGuard（P1）

- **动机**：多端口共享后端 + 数小时评测 ⇒ 热节流/内存增长导致 p99 漂移；官方会把延迟波动纳入可信度。续航 = 部署层稳定。
- **与现有做法的差异**：第 1 轮 IP-03 只做"超预算兜底"；ThermoGuard 做**主动反馈控制**：监测 p99 与温度/队列深度，提前降分辨率/专家数/chunk，避免被动节流。
- **技术可行性**：中–高。温度可能不可得，但 p99 延迟本身是可用代理。
- **落地步骤**：①埋点 p50/p99、队列深度、温度（可得则用）；②设计控制器（简单比例控制即可）；③定义降级阶梯（分辨率→专家数→chunk 长度）；④8 h 压测；⑤导出报告。
- **风险**：①降算力降成功率 ⇒ 只降"不影响当前相位"的算力；②温度不可得 ⇒ 用延迟作为代理；③控制震荡 ⇒ 加死区与最小驻留。

### IP-15 · SeasonVault（P1）

- **动机**：赛季长、提交多，"某轮改坏冠军"是最大尾部风险；需要在统计上控制回归。
- **与现有做法的差异**：常见做法是"最新版覆盖"；我们做 champion–challenger：challenger 必须通过顺序检验才替换，冻结安全版永远可回滚。
- **技术可行性**：高（流程 + 统计）。
- **落地步骤**：①版本/配置/结果注册表；②challenger 用配对 debug 或小样本 scored 做顺序检验（SPRT / α-spending）；③替换阈值预注册；④一键回滚；⑤赛季末做"回归率"复盘。
- **风险**：①检验过于保守 ⇒ 错过真实改进；②多重比较 ⇒ 控制 FWER；③流程开销 ⇒ 自动化。

### IP-16 · FieldModel（P2）

- **动机**：一旦 Runs 页公开，可估计对手任务级强弱；但当前 teaser 是随机占位，不能拟合。
- **与现有做法的差异**：别人可能直接用旧榜单；我们明确"teaser 权重=0，只作结构先验"，等真实 run 记录再用分层贝叶斯更新。
- **技术可行性**：中（依赖数据公开）。
- **落地步骤**：①Runs 页 schema 解析；②对手任务级 Beta 后验；③只作为 RankPilot 的弱先验；④做"用/不用 FieldModel"的消融；⑤若与真实差异大，立即关闭。
- **风险**：①对手数据选择偏差（只公开部分 run）⇒ 只用其作为先验，不单独决策；②过拟合 ⇒ 强正则 + 预注册。

## 3. 符号与定义（C1–C12）

| 符号 | 含义 |
|---|---|
| `θ ∈ Θ` | 候选策略/配置（同一 checkpoint 的不同推理配置也算） |
| `p_i(θ)` | 任务 i 的真实成功率 |
| `S(θ)` | 分数 `= (1/32) Σ_i p_i(θ)`（步骤分与成功率近共线，L1） |
| `n_i` | 任务 i 的试验次数 |
| `\hat S` | 观测分数 `= (1/32) Σ_i X_i/n_i`，`X_i ~ Bin(n_i,p_i)` |
| `R` | 名次 `= 1 + Σ_c 1{\hat S_c > \hat S_us}` |
| `(μ_c, σ_c²)` | 对手 c 的后验 |
| `Δ` | 我们与领跑者的均值差 `μ − μ_L` |
| `Π` | 提交组合 `{(θ_j, k_j)}`；`A` 为聚合规则 `{max, latest, mean}` |
| `E(δ)` | 检测 δ 所需总试验数 |
| `h_j` | 相位 j 的失败风险（hazard） |
| `ρ_res` | 储备比 `(预算 − nominal)/nominal` |

**定义 C1（排名决策）** 决策目标是最大化 `E[U]`，`U = 1{R ≤ k}`（或 `U = −R`）；均值 `S` 只是 `R` 的输入。

**定义 C2（观测模型）** `\hat S = (1/32)Σ_i X_i/n_i`，`X_i ~ Bin(n_i,p_i)`；`E[\hat S]=S`，`Var(\hat S)=V/(32E)`，`V=Σ_i p_i(1−p_i)`，`E=Σ_i n_i`。

**定义 C3（favorite/underdog）** 若 `μ > μ_L` 为 favorite，`μ < μ_L` 为 underdog；`Δ` 的符号决定方差方向（L10）。

**定义 C4（检测预算）** `E(δ) = z²V/(32δ²)`；`δ_min` 为"值得投入的最小效应"。

**定义 C5（信息价值）** 一次 debug/scored run 的 `VOI = E[损失下降] / 成本`，`成本` 用时段数、电池、局数或算力计。

**定义 C6（提交组合）** `Π = {(θ_j,k_j)}`，`k_j` 为该候选的 run 数；`A` 未知时按 minimax regret 选组合与顺序。

**定义 C7（episode 生存）** `P(success) = Π_{j=1}^J (1−h_j)`；相位顺序不影响乘积。

**定义 C8（恢复算子）** 失败后以概率 `q` 恢复、消耗 `c` 预算、最多 `r` 次；可行性要求 `c ≤ 剩余预算`。

**定义 C9（储备比）** `ρ_res = (B − C_nom)/C_nom`；`C_nom` 为名义完成成本。

**定义 C10（部署续航）** 指标向量 `(p99 延迟漂移, 降级率, 内存增长, 温度代理)`；目标是在 8 h 内漂移 ≤10%。

**定义 C11（赛季回归）** 一次提交使真实 `S` 下降超过 `δ_reg` 且被接受，称为回归；用顺序检验控制。

**定义 C12（安全网）** 一个冻结的、已验证可运行的提交 `θ_safe`，任何情况下可回退。

## 4. 引理 L8–L15

**引理 L8（排名噪声）** 在 C2 下，`sd(\hat S)=sqrt(V/(32E))`。若每任务 1 次、`V≈6.0–6.6`，则 `sd≈7.6–8.1 pp`。⇒ 低试验数下名次是随机变量。∎

**引理 L9（检测阈值）** 要在双侧 `z` 水平分辨 `δ`，需 `E ≥ z²V/(32δ²)`；代入 `V=6.0, z=1.96` 得 +1pp→7204、+2pp→1801、+3pp→800、+5pp→288 局。∎

**引理 L10（方差方向性）** 设 `S~N(μ,σ²)`、`L~N(μ_L,σ_L²)`，则 `P(S>L)=Φ((μ−μ_L)/sqrt(σ²+σ_L²))`，且

`∂P/∂σ² = −φ(z)(μ−μ_L)/(2(σ²+σ_L²)^{3/2})`。

故 `μ<μ_L` 时增大 `σ` 提高胜率，`μ>μ_L` 时降低 `σ` 提高胜率。（`σ` 为策略/提交的真实波动；固定均值下比较。）∎

**引理 L11（提交对冲）** 若 `A=max` 且 k 个提交独立，`P(win)=1−(1−p)^k`，随 k 单调增；若 `A=mean`，`P(win)=Φ((μ−μ_L)/sqrt(σ²/k+σ_L²))`，此时 favorite 增大 k 有利、underdog 增大 k 有害。⇒ 聚合规则决定"多样化 vs 集中"。∎

**引理 L12（分配近中性）** Neyman 分配 `n_i ∝ sqrt(v_i)` 的方差为 `(Σ√v_i)²/(32²E)`，均匀分配为 `Σv_i/(32E)`；比值 `(Σ√v_i)²/(32Σv_i) ≥ 0.9987`（当 `v_i∈[0.16,0.25]`）⇒ 每任务分配是二阶项，总试验数 E 是一阶项。∎

**引理 L13（恢复的储备门）** 一次重试成本 `c`，可行 iff `剩余预算 ≥ c`；若 `ρ_res < c/C_nom`，则恢复无法执行，恢复增益≈0。仿真：`ρ_res=0.075` 时 +0.2 pp，`ρ_res=0.375` 时 +6.82 pp。∎

**引理 L14（聚合未知的鲁棒组合）** 若 `A∈{max,mean,latest}` 未知，纯"安全"在 `A=mean` 最优但在 `A=max` 有 regret；纯"高方差"反之。minimax-regret 需要混合/组合，且 `A=latest` 时把安全候选放在最后。∎

**引理 L15（赛季无回归）** 若每次替换以显著性 `α` 进行，M 次提交的族错误率 `≤ 1−(1−α)^M ≈ Mα`；用 `α/M`（Bonferroni）或 α-spending/SPRT 控制；冻结安全网把回归的下行截断。∎

def choose_debug_tasks(post, cost, k=3):
    # VOI ~ expected reduction in P(top-k) uncertainty per unit cost
    return sorted(post.tasks, key=lambda t: -post.voi(t) / cost[t])[:k]

# ===== IP-11 PortfolioSubmit：聚合未知的提交组合 =====
def build_portfolio(cands, A_mode):
    safe  = max(cands, key=lambda c: c.mu)
    risky = max(cands, key=lambda c: c.sigma)
    return {"max": [risky, safe], "mean": [safe], "latest": [risky, safe]}[A_mode]

# ===== IP-13 ReserveGuard：恢复预算 =====
def allow_recovery(state, c_next, reserve_ratio=0.125):
    remaining = state.budget - state.spent
    return remaining - c_next >= reserve_ratio * state.c_nominal

# ===== IP-14 ThermoGuard：p99 反馈控制 =====
def thermo_step(p99, target, temp_proxy, cfg):
    if p99 > target or temp_proxy > cfg.temp_soft:
        return cfg.degrade()      # resolution -> experts -> chunk
    if p99 < 0.8 * target and temp_proxy < cfg.temp_cool:
        return cfg.recover()      # hysteresis / min dwell
    return cfg

## 8. 预注册判据与处置

| 判据 | 门槛 | 未达标处置 |
|---|---|---|
| 排名噪声（E619） | 与 L8 预测一致 | 若偏差大 ⇒ 检查是否多任务相关/协议有额外平滑 |
| 检测预算（E620） | 实测在预测 0.7–1.5× | 若更贵 ⇒ 提高 `δ_min`，只赌 ≥5pp |
| RankPilot（E621） | 一致率 ≥70% | 退回简单规则（favorite/underdog + 固定阈值） |
| 方差方向（E622） | 方向正确 | 若反向 ⇒ 检查是否聚合=mean 或对手相关 |
| 配对（E624） | 局数下降 ≥30% | 若无效 ⇒ 会话噪声小，用普通 A/B |
| 恢复（E628） | 有储备 +≥5 pp | 若 <2 pp ⇒ 恢复算子无价值，关闭 |
| ReserveGuard（E629） | 超时↓且成功率不降 | 若降 ⇒ 放宽早停阈值 |
| ThermoGuard（E631） | 漂移 ≤10% | 若超 ⇒ 降分辨率/专家数，或单端口复制 |
| SeasonVault（E632） | 族错误 ≤5% | 若超 ⇒ 更保守的 α/更多样本 |
| 协议鲁棒（E636） | 不劣于基线 | 若劣 ⇒ 收窄假设，回到"安全单提交" |
| 端到端（E638） | 名次 ≥+1 或 `P(top-3)` ≥+10 pp | 逐 IP 消融，砍无效项 |
