# 第 8 轮 · RM-VLA：把评分表变成奖励机器，事件/惯性降为验证通道

> 检索/复核日期：2026-10-24（UTC）。赛事身份确认不变：用户所指是宇树科技的 **UniBot 世界挑战赛**（unibot.unitree.com），G1 + Dex1、32 项桌面任务、通才单模型赛道、选手自部署 + 官方远程真机 API 评测。状态文件已到第 7 轮（PILOT-GPR），本轮按续写处理，不推倒重来。本轮三个灵感词是「奖励设计」「事件相机」「惯性测量单元」。我先各自钉到本轮核实到的官方事实上，再合成主判断：**排名规则其实是“成功率优先、步骤分只做 tie-break”，所以第 7 轮“步骤分约 60%”的预算逻辑必须校正；正确用法是把公开评分表做成单 checkpoint 内的奖励机器（SSRM）+ 进度/验证头，用稠密奖励训练、用关键时刻 best-of-N 提成功率、用 Φ 下降检测人类 undo 并回滚恢复；事件相机和 IMU 都不在 API 里，真硬件路线砍掉，降级为 VCE（虚拟变化事件）和 PCR（本体感受接触残差）两个软件验证通道。**

## 0. 本轮先核实：四个会改变策略的事实

### 0.1 排名是“成功率优先，步骤分只做 tie-break”

官方参赛手册（中文 [S1]、英文 [S2]）写得很明确：实时榜单按 32 个任务的 **总平均成功率** 排序；成功率相同才看 **总平均步骤分**；仍相同则提交日期较早者靠前。网站首页仍写“按平均成功率与步骤分综合排序” [S3]，但手册的 lexicographic 规则更具体，应以手册为准。

这修正了第 7 轮的一个倾向：第 7 轮把“终局步骤占 39.8%、放置类步骤约 59.7%”当作“步骤分大头”的主目标。现在必须改成：

```text
主目标 = P(全部步骤完成) = 成功率
辅助   = E[步骤分]（只在成功率打平时决定名次）
训练   = 步骤分可以作为稠密信号，但不能为了步骤分牺牲终局成功
```

换句话说，**步骤分是训练信号和 tie-break，不是主目标**。任何奖励设计都必须服务成功率；如果模型学会“做易步骤、停在半路、甚至假完成”，步骤分再高也赢不了。

### 0.2 每个任务 10 次，5 类泛化各 2 次；单次 180 秒

手册 [S1][S2]：每个任务执行 10 次独立运行，包含 5 种泛化类型（位置、干扰物、桌面背景、未见物品、人为干扰），每种各出现 2 次；单次真机执行最大允许 180 秒，超时记失败。32×10=320 个计分 episode。

这个结构意味着：**泛化轴是重复测量的，不是一次性的**；每个轴只有 2 次/任务，单任务噪声很大，必须用配对设计、bootstrap 置信区间和跨任务聚合，不能根据单个任务的小波动下结论。第 7 轮说的“320 trials、p≈0.3、SE≈2.56pp”仍然成立，但 +2pp 级别的差异基本不可分辨，目标应放在 +5pp 以上或机制性改进。

### 0.3 榜单仍是占位，不能分析“真实头部方案”

本轮实测 [S4][S5][S6]：

- `leaderboard.html` 仍是「即将发布 / Coming Soon」；`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`。
- 8 个模型（MolmoAct2 29.7/39.0、WALL-OSS-0.5 28.5/38.9、DreamZero 27.9/37.9、Spirit-v1.5 25.9/34.4、DM0 23.5/31.7、PI-0.5 22.8/30.6、GigaBrain-0 22.6/29.5、GR00T N1.5 20.5/28.1）是脚本生成的占位数据。
- `runs.html` 也是 256/256 占位，详情页明确写“视频占位”。

**用户说的“榜首成功率也不到 30%”来自占位数据，不是真实团队。** 我们不能从这些数字推断谁强谁弱，也不能推断真实头部方案的做法。唯一可谨慎使用的量：8 个占位模型的“步骤分 − 成功率”平均约 +8.6pp（最高 +9.3pp），这与“多数失败发生在做完大部分步骤、倒在最后一步”一致；但这只是弱先验，必须标“未核实”。

### 0.4 API 没有 IMU，也没有事件相机；只有 4 路 RGB + 关节/EE/夹爪/下半身

提交 README [S7] 的观测目录只有：

- 4 路 RGB：`cam_left_high`、`cam_right_high`、`cam_left_wrist`、`cam_right_wrist`，480×640；
- 左右臂关节 `[7]`、左右 EE 位姿 `[6]`（base 系，xyz+rpy）、夹爪 `[1]`；
- `observation.state.lower_body` `[15]`；
- `observation.language` 单字符串。

数据集 README [S8] 明确：`lower_body` = 双腿（hip×3、knee、ankle×2）+ 腰（yaw、roll、pitch），**不是 IMU**；`state_torso`、`waist_state_joint`、`state_d435` 在数据集里有，但 API 不暴露。事件相机更不在观测里。

因此本轮先做两个“砍”：

- **真事件相机：砍。** 不能加传感器；远程 API 只给 RGB。可做的替代是连续帧差分构造的 VCE。
- **真 IMU：砍。** API 不暴露 IMU；`lower_body` 是关节角。可做的替代是“指令关节目标 − 实测关节位置”的跟踪残差 PCR。

这两个“砍”不是消极结论，而是把资源从不可行的硬件路线拉回可落地的软件验证通道。

## 1. 三个灵感词，各自钉到官方事实

### 1.1 奖励设计：评分表是现成的 reward machine，但要用对

32 个任务的 `score_steps` 已公开 [S9]（T27 30/30/40、T10 30/30/40、T07 30/30/40…），满分统一 100，成功 = 所有步骤完成。这可以直接写成一个有限状态奖励机器（Reward Machine，RM）：

```text
状态 u_k   = 已完成 k 步
转移       = 谓词 P_{k+1}(s) 为真时 u_k → u_{k+1}
终局 u_K   = 成功闸门
```

用它做三件事：

1. **稠密训练信号**：定义势函数 Φ(s) = 已完成步骤权重 + 当前步部分进度；稠密奖励 r_t = Φ(s_{t+1}) − Φ(s_t)。这是 potential-based reward shaping，理论上不改变最优策略（Ng et al. 1999 [S20]）；再加一个终局 bonus 对齐“成功率优先”。
2. **进度/验证头**：在同一个 checkpoint 上加 progress head（预测 Φ 或 ΔΦ）和 verifier head（给候选 action chunk 打分），用 pairwise 排序训练；推理时在终局/高权重步做“关键时刻 best-of-N”。证据链：VLAC 的 pairwise 进度 critic 在真机 4 个任务把成功率从约 30% 提到约 90%（200 episodes）[S12]；RARM 的 confidence-gated progress reward [S13]；DenseReward 的失败合成稠密奖励 [S14]；VLA-ATTC 的 adaptive test-time compute + relative action critic [S16]；DiVeR 的 decision-critical verifier [S17]；Verify, Act, Distill 把 TTC 收益蒸馏回策略 [S18]。
3. **奖励下降检测**：人类干扰备注里大量是“先完成再撤销”——T27 叠了第二个又拿下、T19 拉上又拉开、T14 拧开又拧回、T17 合上又打开 [S9]。RM 检测 Φ 从高到低，回滚到上一个稳定步，触发恢复。这是第 7 轮 NRB 的正式化。

关键校正：**不要用步骤分做 reward hacking**。如果只最大化步骤分，模型会学会做易步骤、停在半路、甚至“假完成”。必须用终局闸门 + 几何谓词 + 成功头校准，把步骤分当辅助信号。排名是成功率优先，训练奖励也必须成功率优先。

### 1.2 事件相机：真传感器不可行，虚拟变化事件可做验证通道

事件相机的核心优势是“只对相对运动产生事件”：夹爪上的事件相机看被夹物体，夹稳时无事件，滑动时立刻有事件（2kHz 级）[S21][S22]。这在 UniBot 里有两个启发：

- **滑动/掉落检测**：腕部相机随夹爪运动，夹稳的物体在腕部图像里近似静止；物体滑动/掉落时，腕部图像的帧差/变化事件会突增。30fps 做不到 2kHz，但对“缓放后的 settle 校验”和“慢滑”够用。
- **人为干扰起始检测**：头部相机看到人手进入、物体被平移，帧差事件比语义分割更便宜、更抗背景。

所以本轮把“事件相机”降级为 **VCE（Virtual Change Events）**：对连续帧做 log-intensity 差分、阈值化、聚合成正/负极性张量，作为 verifier/SVL 的辅助通道，不做主策略输入。真事件相机：砍。

需要区分：EventVLA [S23] 是“event-driven visual evidence memory”，不是事件相机传感器；它对我们有启发的部分是“关键帧/证据记忆”，不是硬件。我们不在本轮把 EventVLA 当主路径，只借用“变化触发的记忆”思想。

### 1.3 惯性测量单元：真 IMU 不可行，本体感受接触残差可做

G1 有 IMU，但 API 不暴露；`lower_body` 是关节角 [S7][S8]。可做的“IMU 启发”信号是 **PCR（Proprioceptive Contact Residual）**：

- 我们知道自己下发的关节目标 q_cmd（action）和 API 返回的实测 q_meas；r_t = q_cmd − q_meas 及其差分。PD 控制下，接触/卡住/碰撞会产生跟踪误差；夹爪开度与物体反力也会反映在残差上。
- 这个信号是“准触觉”的：插入卡住、放置压到桌面、抓取没夹住、物体滑动，都会改变残差。Blind Dexterity 已经证明 G1 的关节编码器 + PD 控制可以形成接触通道 [S24]；SafeLoop 用 vision+proprioception 做风险预测与 rollback [S25]；Uni-VLaT 用本体感受/触觉预测增强 VLA [S26]。
- 用途：SVL 的接触/到位判定、插入的“卡住”检测、抓取成功校验、chunk 边界的闭环修正。真 IMU：砍；PCR：保留为辅助通道。

## 2. 主判断：从“攻终局放置”升级为“用奖励机器攻成功率”

第 7 轮的判断“终局放置是闸门、跨五轴杠杆”仍然成立，但有两个修正：

1. **排名是成功率优先**，所以终局放置的价值主要在“闸门”，不是“步骤分大头”。步骤分只在成功率相同时才起作用。资源应优先保证“完成全部步骤”的概率，而不是“多拿部分分”。
2. **终局放置只是 reward machine 的最后一个状态**。真正可复用的机制是：用公开评分表做稠密奖励/验证/恢复，覆盖所有步骤、所有泛化轴。这样比只攻放置更通用，也更符合“单模型 32 任务”的设定。

于是本轮主线：

```text
RM-VLA = 单 checkpoint（WLA/GPR 主干 + action expert）
       + SSRM 奖励机器
       + progress head
       + verifier head
       + PCR/VCE 辅助通道
       + 关键时刻 best-of-N
       + 奖励下降恢复
```

预期收益：

- 成功率 +Δ 是主收益；步骤分作为 tie-break 的次要收益。
- 训练信号从“稀疏成功”变成“每步有反馈”，样本效率更高。
- 验证/恢复能力直接覆盖人为干扰轴的 undo 剧本。
- 单模型合规：所有头在同一个 checkpoint；VCE/PCR 是确定性特征，不是第二个模型。

## 4. 风险与合规（先立后破）

- **单模型边界**：progress/verifier 头必须是同一 checkpoint 的一部分；推理时不得调用第二个学习模型。VCE/PCR 是确定性特征。模型卡写清。
- **奖励黑客**：RM 状态只由几何谓词推进，progress head 只做排序/加权；终局成功头用真实 episode 标签校准；best-of-N 只在策略分布内采样。
- **标签噪声**：步骤边界用“时间排序 + 少量人工标签 + 几何谓词”三重；不追求全 32 任务精标。
- **延迟**：best-of-N 只在终局/高权重步/Φ 下降时触发；共享 backbone，batch 采样；p99 超预算就降 N 或关。
- **VCE 30fps 限制**：只做辅助验证，不做高速控制；与 PCR 互补。
- **PCR 噪声**：PD 刚度/重力/摩擦会污染残差；用相对变化和任务内校准，不做绝对力估计。
- **规则未读部分**：外部数据/预训练权重是否允许仍未完全确认；默认只用官方数据 + 公开预训练模型，外部实验室数据默认 OFF，邮件确认后再开。
- **榜单占位**：不根据占位数据调参；真实榜单发布后重跑假设。

## 5. 一句话押注

**把公开评分表变成单 checkpoint 内的奖励机器与验证器：用 SSRM 稠密奖励训练、用 progress/verifier 头在终局和高风险步做保守 best-of-N、用 Φ 下降检测人类 undo 并回滚恢复；事件相机和 IMU 不追硬件，降级为 VCE/PCR 两个软件验证通道——这是本轮最值得押注的方向。**

## 0. 产物摘要

### 0.1 一句话

### 0.3 预期收益（可证伪）

- 主收益是 **成功率**：终局步/高权重步 +Δ ⇒ 全局成功率约 +Δ×q（q=到达终局步的通过率，估 0.5–0.7），且五轴同时受益。
- 次收益是 **步骤分**：只在成功率打平时决定名次；不作为主目标。
- 目标：成功率 +5pp（320 episodes、p≈0.3、SE≈2.56pp，+5pp 约 90% 概率排名更高；+2pp 基本不可分辨）。
- 可证伪点：若 T27/T10 调试槽里 verifier-guided best-of-N 的终局成功率提升 <5pp，则“测试时选择”假设不成立，回退到纯 SSRM + SVL；若 progress head 的 pairwise 准确率 <65%，则进度信号不可用，回退到几何谓词。

| 关系 | 内容 |

## 2. 评分算术与奖励设计

### 2.1 lexicographic 目标

```text
J = 1[success] + β · step_score,   β 很小（如 0.1）或直接用 lexicographic
success = 1[所有步骤完成]
step_score = Σ w_i · 1[步骤 i 完成]  （假设每步二值；若官方有部分分，按官方公式）
```

训练时不要直接把 `step_score` 当唯一奖励；否则模型会“刷步骤分”。正确做法：

- **成功头**：BCE 预测 episode 成功；用真实 demo（成功）和合成失败/undo（失败）训练。
- **进度头**：预测 Φ/ΔΦ；只用于排序/加权/验证，不直接推进 RM 状态。
- **动作损失**：用 `1 + α·ΔΦ + γ·success` 加权（reward-weighted BC / advantage-weighted regression）。
- **终局 bonus**：`B·1[terminal]`，B 足够大，保证“完成全部步骤”优先于“多拿部分分”。

### 2.2 SSRM 形式化

对任务 t，步骤权重 `w_1…w_K`，`Σw=100`。定义：

```text
u_k        = 已完成 k 步（k=0…K）
p_k(s)     ∈ [0,1] = 当前步 k 的部分进度（progress head 或几何量）
Φ(s)       = Σ_{i≤k} w_i + w_{k+1}·p_{k+1}(s)   if k<K
           = 100                                if k=K
P_k(s)     ∈ {0,1} = 第 k 步的几何/事件谓词
transition = u_k → u_{k+1}  iff P_{k+1}(s)=1
```

稠密奖励：

```text
r_t = Φ(s_{t+1}) − Φ(s_t)
      − λ·1[undo_t]          # 人类撤销/物体被移走
      + B·1[u_K]             # 终局 bonus
```

性质：

- 若 `λ=B=0`，`r_t` 是 potential-based shaping，理论上不改变最优策略（Ng et al. 1999 [S20]）。
- `B` 和 `λ` 是**有意偏离** potential-based：`B` 对齐“成功率优先”，`λ` 惩罚 undo。它们改变最优策略，但方向与真实目标一致。
- RM 的状态推进只由 `P_k` 决定；`p_k` 只影响奖励形状，不决定状态。这防止 progress head 用“看起来像完成”骗过状态机。

### 2.3 为什么不用 step-score farming

如果训练奖励 = step_score，模型的最优策略可能是：

- 只做容易的前几步，停在半路（拿到部分分）；
- 反复做“看起来完成”的动作（假完成）；
- 避免高风险的终局放置（因为失败会丢掉终局分，但前几步已经拿到）。

这会直接损害成功率，而成功率是排名主键。SSRM 的终局 bonus + 成功头 + 几何谓词 + undo 惩罚，就是为了把“刷步骤分”压下去。

### 2.4 反奖励黑客的四道闸

1. **状态闸**：RM 只由几何/事件谓词推进，不由 progress head 推进。
2. **成功闸**：verifier/成功头用真实 episode 标签校准；best-of-N 只在策略分布内采样。
3. **终局闸**：`B` 大，且成功头与动作头共享特征；不允许“局部最优但终局失败”的策略占优。
4. **审计闸**：所有学习组件在同一个 checkpoint；模型卡披露 SSRM/VCE/PCR 的确定性逻辑；不调用第二个模型。

### 2.5 统计功效

- 320 episodes；p≈0.3 时 SE≈2.56pp。
- +5pp 约 90% 概率排名更高；+2pp 基本不可分辨。
- 每个泛化轴只有 2 次/任务，轴级结论必须跨 32 任务聚合；不要用单任务轴级差异下结论。
- 用配对 bootstrap（同任务、同轴、同初始条件）降低方差。

### 3.2 单 checkpoint 三头

- **Action expert**：flow matching / diffusion，输出 `action_chunk_size` 步的 EE 或 joint 动作。
- **Progress head**：2 层 MLP（256 hidden），输入 `[f_t; q_t; e_t]`，输出 `Φ_hat ∈ [0,100]` + `K` 个步骤 logits。`f_t` 是 VLA 池化特征；`q_t` 是关节/EE/夹爪/PCR；`e_t` 是 VCE（可选）。
- **Verifier head**：2 层 MLP，输入 `[f_t; action_chunk_embedding; q_t; e_t]`，输出成功 logit / 期望 Φ_{t+H}。action chunk embedding 由 action expert 的中间特征池化得到。

三个头共享 backbone；总参数量增加 <2%。推理时一次 backbone 前向，多个头并行；best-of-N 只 batch 采样 action expert，不重复 backbone。

### 3.3 SSRM 状态机

```python
class SSRM:
    def __init__(self, task_info):
        self.steps = task_info["score_steps"]      # [{en, zh, score}]
        self.K = len(self.steps)
        self.weights = [s["score"] for s in self.steps]
        self.k = 0
        self.phi = 0.0
        self.stable_phi = 0.0
        self.stable_k = 0

    def update(self, obs, progress_hat, predicates):
        # 状态推进只由谓词决定，不由 progress_hat 决定
        while self.k < self.K and predicates[self.k](obs):
            self.phi += self.weights[self.k]
            self.k += 1
            self.stable_phi = self.phi
            self.stable_k = self.k
        # 部分进度只影响奖励形状
        partial = 0.0 if self.k == self.K else self.weights[self.k] * progress_hat
        self.phi = sum(self.weights[:self.k]) + partial
        return self.phi

    def detect_undo(self, obs, predicates):
        # 已完成步骤的谓词从 1→0，或 Φ 突降
        if self.k > 0 and not predicates[self.k - 1](obs):
            return True
        return False
```

### 3.4 Progress head

**训练目标**（不需要全量精标）：

1. **时间排序**：同一 demo 内 `t1 < t2` ⇒ `Φ(t1) < Φ(t2)`；跨步骤边界时 margin = 权重差。
2. **步骤分类**：小规模人工标签（8 任务 × 200 帧）→ 步骤 CE。
3. **端点校准**：`Φ(start)=0`，`Φ(terminal)=100`。
4. **undo 下降**：合成 undo 帧 ⇒ `Φ` 下降。

损失：

```text
L_prog = L_pair + λ1 L_step + λ2 L_cal + λ3 L_undo
L_pair = max(0, margin − (Φ(t2) − Φ(t1)))
```

优点：33k demo 的时间顺序是免费标签；人工只需标少量步骤边界；pairwise 比回归更抗标定误差。

### 3.5 Verifier head

**正负样本**：

- 正：demo 在状态 `t` 的真实 action chunk。
- 负：
  - 异任务 chunk（任务不匹配）；
  - 时间反向 chunk（动作顺序反了）；
  - 扰动 chunk（加噪/缩放/方向翻转）；
  - undo 状态的 chunk（人类刚撤销）；
  - 失败合成轨迹的 chunk。

损失：

```text
L_ver = L_pairwise + λ4 L_success_BCE + λ5 L_cal
L_pairwise = max(0, margin − (s(x, a+) − s(x, a−)))
```

推理：

```text
N 个候选 chunk → verifier 分数 s_i
若 max s_i − second s_i > τ 且 max s_i > s0：选 max
否则：选第一个（保守回退）
```

### 3.6 Adaptive best-of-N

触发条件（满足任一）：

- 当前步骤是终局步（`k=K−1`）；
- 当前步骤权重 ≥40；
- progress head 的 ensemble 方差 > τ_u；
- `Φ` 下降/谓词失败；
- 连续 `m` 个 chunk 的 ΔΦ≈0（停滞）。

预算：

| 场景 | N | 说明 |
|---|---:|---|
| 终局步 | 4 | 成功闸门，值得多采样 |
| 高权重/不确定 | 2 | 折中 |
| 其余 | 1 | 不增加延迟 |

延迟控制：

- backbone 只前向一次；N 个 chunk 由 action expert batch 采样；
- verifier batch 打分；
- 目标 `get_action` p99 <150ms；超预算则 N 降级或关闭非终局触发；
- 180s episode 预算内，终局最多 2 次 best-of-N。

### 3.7 SVL 2.0：PCR/VCE 验证的落点闭环

```python
def place_and_verify(step, obs, plan, budget=2):
    for attempt in range(budget + 1):
        anchor = PGL.render(plan, obs)
        ctx    = ICR.retrieve(step, obs, k=4)
        for chunk in stream(policy.act(obs, anchor, ctx, s=step)):
            send(chunk)
            if predicate_met(step, obs) and pcr_contact(obs) and vce_stable(obs):
                break
        if not predicate_met(step, obs):
            plan = revise(plan, obs, reason=diagnose(step, obs)); continue
        open_gripper(slow=True); sleep(0.5)
        if stable(step, obs, window=0.5) and pcr_released(obs) and vce_stable(obs):
            return True
        if repairable(step, obs):
            plan = nudge_plan(step, obs)
        else:
            regrasp(step)
    return False
```

- `pcr_contact`：`|q_cmd − q_meas|` 或 EE 残差超过任务阈值。
- `vce_stable`：腕部 VCE 能量低于阈值（物体相对夹爪静止）。
- `stable`：物体相对位姿 0.5s 内位移 <ε + 谓词保持。
- 预算：普通任务 ≤2 次；长程任务（T16/T17/T31）≤1 次；Endurance Governor 兜底 180s。

### 3.8 NRB 2.0：奖励下降回滚

官方 human 备注 [S9] 是现成剧本：

| 任务 | 官方备注（节选） | 场景化 | 恢复目标 |
|---|---|---|---|
| T27 | 叠了第二个之后拿下第二个 | 移除 bowl2 | 重新放置 bowl2 → 继续 bowl3 |
| T19 | 拉上拉链之后拉开 | 拉开拉链 | 重新拉合 |
| T14 | 拧开盖子之后拧动回来 | 盖回瓶盖 | 再拧开 → 倒药 |
| T17 | 笔盒合上之后手动打开 | 打开盒盖 | 重新合上 |
| T24 | 物品快到了然后放回传送带起点 | 目标远离 | 重新抓取→放置 |
| T10 | 将插头拔起 | 拔出插头 | 重新抓取→插入 |
| T12 | 中途把锁拿走 | 锁被移走 | 重新定位锁→继续翻环 |

训练：把“撤销前”和“撤销后恢复”作为一对，`Φ` 从高→低→高；动作损失对恢复段加权。推理：SSRM 检测 `Φ` 下降 → 回滚到 `stable_k` → 用 ICR/OPT 重新执行当前步。

### 3.9 与 PGL/OPT/ICR 的接口

- **PGL**：槽位/区域 → 2D 锚点 → 6D 位姿；给 action expert 和 verifier 提供显式目标。
- **OPT**：K 条演示的容器系释放位姿统计（中位数 + 离散度）；给 PGL 提供度量目标；离散度决定直接执行/伺服/退化。
- **ICR**：关系/运动检索；给 action expert 提供上下文 token 和动作先验；给 verifier 提供“相似场景的成功 chunk”作为正样本。
- 三者不再单独承担“攻放置”的主线，而是 SSRM 的动作先验/验证特征。

## 5. 事件/惯性代理

### 5.1 VCE（Virtual Change Events）

**定义**：对连续帧 `I_{t-1}, I_t`：

```text
ΔL = log(I_t + ε) − log(I_{t-1} + ε)
E+ = 1[ΔL > C],  E− = 1[ΔL < −C]
VCE_t = stack(E+, E−)  # 2 通道，可再堆 2–3 帧
```

**用途**：

- 腕部 VCE：夹稳物体时能量低；滑动/掉落时能量高 → SVL 的 slip/drop 验证。
- 头部 VCE：人手进入、物体被平移、背景变化 → human/distractor 轴的干扰起始检测。
- verifier/progress head 的辅助输入：变化区域比全局外观更抗背景。

**训练**：从 demos 计算 VCE；用 PCR/谓词做弱标签；自监督“预测下一帧 VCE”可选。**不需要事件相机数据集。**

**风险**：30fps 不是真事件相机；快速滑动可能漏检；帧差对光照/阴影敏感；可能与光流冗余。**定位：辅助/探索，不做主策略。**

### 5.2 PCR（Proprioceptive Contact Residual）

**定义**：

```text
r_t = q_cmd,t − q_meas,t          # 关节跟踪残差（7+7 维）
ṙ_t = r_t − r_{t-1}
e_t = EE_pose_cmd − EE_pose_meas  # EE 残差（6 维）
g_t = gripper_cmd − gripper_meas  # 夹爪残差
PCR_t = [r_t, ṙ_t, e_t, g_t]
```

**用途**：

- 插入/卡住：残差突增 → 触发 wiggle/retreat/retry。
- 放置压桌：垂直方向残差 → 触发缓放/停止。
- 抓取成功：夹爪残差 + 物体相对运动 → 抓取校验。
- 滑动：残差 + VCE 同时异常 → 重抓。
- chunk 边界：用残差修正下一 chunk 的目标。

**训练**：不需要新数据；用 demos 的 `action.*` 与下一帧 `observation.state.*` 计算残差；用谓词/接触事件做弱标签；任务内标准化。

**风险**：PD 刚度/重力/摩擦会污染残差；API 不提供力矩；残差可能很小。**定位：辅助/验证，不做绝对力估计。**

### 5.3 为什么不是真传感器

| 路线 | 可行性 | 原因 |
|---|---|---|
| 真事件相机 | 不可行 | API 只给 4 路 RGB；不能加传感器；远程评测 |
| 真 IMU | 不可行 | API 不暴露 IMU；`lower_body` 是关节角 |
| 外部传感器 | 高风险 | 评测在官方真机；规则未明确允许；部署侧无法保证 |
| VCE/PCR | 可行 | 纯软件；用现有观测/动作；单模型合规 |

### 5.4 消融设计

- VCE on/off；腕部 vs 头部；阈值 C；帧数。
- PCR on/off；关节 vs EE vs 夹爪；任务内标准化 vs 全局。
- VCE+PCR vs 单独；在 SVL 的 slip/drop 检测上的 precision/recall。
- 延迟：VCE/PCR 特征计算 <5ms；不影响 p99。

## 7. 实验设计

### 7.1 离线（每天）

| 指标 | 目标 | 说明 |
|---|---|---|
| 步骤谓词 F1 | >0.8 | 8 个精标任务 |
| Φ Spearman | >0.7 | held-out demos |
| progress pairwise acc | >65% | 同 demo 时间对 |
| verifier pairwise acc | >65% | 正/负 chunk 对 |
| verifier ECE | <0.1 | 成功概率校准 |
| best-of-N oracle gap | N=4 比 N=1 高 ≥5pp | 离线候选集 |

### 7.2 本地（每周）

- TCLB 降级为“离线相对比较台”：replay + 合成扰动，只做失败挖掘，不做模型选择。
- 失败分类：抓空、放偏、插入卡住、掉落、undo 未恢复、超时。
- 每个失败片段标注 Φ 轨迹，检查是“进度头错”还是“动作头错”。

### 7.3 平台（版本门）

- 不计分单任务调试槽 [S11]：每个大版本 1 槽。
- 任务选择：T27（叠碗=放置门控）、T10（插排=插入）、T19（拉链=闭合/undo）、T24（传送带=人为干扰）。
- 判定：终局步成功率 ≥+10pp 且无回归才允许进计分跑。
- 计分跑：W7 中期、W8 终期；若只允许 1 次，则 W8 唯一一次。

### 7.4 指标

- 主：总平均成功率。
- 次：总平均步骤分（tie-break）。
- 诊断：5 轴×2 的分轴成功率、每步完成率、time-to-success、undo 恢复率、false completion rate、p50/p99 延迟。
- 安全：超时率、碰撞/掉落率、人工接管次数（若允许）。

### 7.5 消融

| ID | 配置 | 验证 |
|---|---|---|
| E0 | WLA 基线 | 复现 |
| E1 | +SSRM | 步骤状态/防跳步 |
| E2 | E1+progress | Φ 排序/加权 |
| E3 | E2+verifier | 候选排序 |
| E4 | E3+best-of-N | 终局成功率 |
| E5 | E4+PCR/VCE | slip/undo 检测 |
| E6 | E5+NRB 2.0 | undo 恢复 |
| E7 | E6+蒸馏 | 延迟/部署 |

消融：N∈{1,2,4,8}；触发条件；terminal bonus B；pairwise vs 回归；PCR/VCE on/off；undo 惩罚 λ；progress 加权 vs DPO。

### 7.6 统计

- 320 episodes；p≈0.3；SE≈2.56pp。
- 配对 bootstrap（同任务/同轴/同初始条件）；报告 95% CI。
- 轴级结论必须跨 32 任务聚合；单任务轴级差异只做假设生成。
- 预注册主指标（成功率）和停止条件，避免 p-hacking。

## 8. 创新点清单（持续迭代；动机/差异/可行性/资源/步骤/风险/状态）

> 状态：押注=本轮主线；保留=沿用；升级=旧点被改造；降级=保留但不再是主回路；砍=不做。

### I1 SSRM 评分步骤奖励机器（升级 SSG，押注）

- **动机**：官方 score_steps 公开；排名成功率优先；需要稠密信号但不能刷步骤分。
- **与现有方案差异**：第 7 轮 SSG 只是状态机；SSRM 增加势函数 Φ、终局 bonus、undo 惩罚、奖励下降检测；状态只由几何谓词推进。
- **技术可行性**：确定性代码 + 一个小 progress head；32×5 复述可精确匹配；无需新数据。
- **所需资源**：1 人周；CPU；8 个任务的谓词标定。
- **落地步骤**：解析 info.json → 步骤图 → 谓词 → Φ → reset 接线 → 离线回放验证。
- **风险**：谓词噪声；语言未覆盖；reward hacking。缓解：几何谓词 + 嵌入兜底 + 成功头校准。
- **状态**：押注。

### I2 Progress head（新增，押注）

- **动机**：33k demo 的时间顺序是免费进度标签；稠密 Φ 可做数据加权、验证、恢复。
- **与现有方案差异**：不是独立 VLM critic，而是同一 checkpoint 的小头；pairwise 排序 + 少量步骤标签；关系/物体中心特征。
- **技术可行性**：高；WLA 特征 + 2 层 MLP；8 任务 × 200 帧标签即可起步。
- **所需资源**：8×H100 2–3 天；标注 1 周；无新传感器。
- **落地步骤**：特征抽取 → 时间对/跨步对 → pairwise + CE + 校准 → 离线评估 → 接入 SSRM。
- **风险**：标签噪声；任务干扰；OOD。缓解：pairwise、任务 embedding、置信度门控。
- **状态**：押注。

### I3 Verifier head + adaptive best-of-N（新增，押注）

- **动机**：测试时选择是把算力换成成功率的直接杠杆；VLA-ATTC/DiVeR/Verify Act Distill 证据一致。
- **与现有方案差异**：只在终局/高权重/不确定/undo 时触发；共享 backbone；保守回退；单 checkpoint。
- **技术可行性**：中；flow 采样可 batch；verifier 小头；延迟可控。
- **所需资源**：1–2 周；GPU 推理；正负样本对。
- **落地步骤**：构造正负对 → 训练 → 触发策略 → 延迟压测 → 离线 oracle gap → 调试槽。
- **风险**：verifier 过自信；延迟；分布漂移。缓解：pairwise + 校准 + margin 门控 + 只终局触发。
- **状态**：押注。

### I4 PCR 本体感受接触残差（新增，支撑）

- **动机**：API 无 IMU；但 q_cmd−q_meas 是现成的接触/卡住/滑动信号；G1 关节编码器可形成接触通道。
- **与现有方案差异**：不假设力矩/触觉；用指令−实测残差 + EE/夹爪差分；任务内标准化。
- **技术可行性**：高；API 有 joint/EE/gripper；无需新数据。
- **所需资源**：无额外数据；1 人周标定。
- **落地步骤**：计算残差 → 弱标签 → SVL 接触/卡住判定 → 消融。
- **风险**：PD 刚度/重力/摩擦污染；残差小。缓解：相对变化、任务内校准、与 VCE 互补。
- **状态**：支撑。

### I5 VCE 虚拟变化事件（新增，探索）

- **动机**：API 无事件相机；帧差变化事件可做滑动/人手/背景变化检测；抗外观。
- **与现有方案差异**：不是真事件相机；软件层 log-diff 极性张量；只做辅助验证。
- **技术可行性**：中；30fps 限制；视频处理便宜。
- **所需资源**：无新传感器；1–2 周。
- **落地步骤**：log-diff → 极性张量 → 腕/头特征 → SVL/verifier 接入 → 消融。
- **风险**：30fps 漏检；光照/阴影噪声；与光流冗余。缓解：只做慢滑/settle/人手检测；与 PCR 互补。
- **状态**：探索。

### I6 SVL 2.0（升级）

- 第 7 轮 SVL 的“缓放→稳定→重试”保留；新增 PCR 接触、VCE 滑动、SSRM 终局谓词；预算 ≤2 次（长程 ≤1）。
- 风险：耗时/误判；缓解：双阈值 + 总时长守卫。

### I7 NRB 2.0（升级）

- 第 7 轮 NRB 的官方备注剧本保留；新增 Φ 下降检测、回滚到 stable_k、恢复段加权。
- 风险：备注编号含义未核实；缓解：同时覆盖通用扰动。

### I8 PGL/OPT/ICR（保留，重新定位）

- PGL/OPT/ICR 仍是终局放置的动作先验/验证特征；不再单独承担“攻放置”主线。
- 风险：透明/布料容器位姿估计失败；缓解：分桶回退到 ICR/锚点伺服。

### I9 L2L 产学研数据协议（保留，低优先）

- 背景/位置轴的多样性仍靠实验室网络；但外部数据规则未完全确认，默认 OFF。
- 资源：3 实验室 × 2 任务 × 100–200 条；协调 2–3 人。
- 风险：规则不允许；缓解：先邮件确认，默认只用官方数据。

### I10 DebugLoop（保留，流程）

- 不计分单任务调试槽做发布门；每大版本 1 槽；任务 T27→T10→T19→T24。
- 风险：槽位稀缺/规则变化；缓解：TCLB 离线兜底。

### I11 GPR-VLA + WLA 底座（保留）

- 单一 checkpoint；Apache-2.0；24GB 可微调；承接 SSRM/progress/verifier 接口。

### I12 TLE/ACP/GF（保留，修剪）

- 只服务步骤相位、放置标签、合成失败；不做全 32 任务高保真孪生。

### I13 TCLB / FLEET（降级）

- TCLB 降为离线相对比较台；FLEET 的事实（N 端口、状态隔离、RTC 延迟、健康检查）保留为工程检查单，不再当“第六轴”。

### 已砍清单（跨轮）

- 真事件相机；真 IMU；独立 VLM critic；全 world model / WMA-0 进主路径；步骤分 farming；每任务 LoRA/模型合并；全 32 任务高保真孪生；自由仿真数据；运行时仿真/MPC；仿真 RL；布料/拉链/透明全物理。
