## 0. 本轮先核实：六个事实，其中两个改变了优先级

### 0.1 榜单页标了「Ranking · Live」，但数据仍是占位

`leaderboard.html` 现在渲染出 8 个模型（MolmoAct/DexHacker 29.7%、WALLOSS/Generalist Robotics 28.5%、DreamZero/World Model Lab 27.9%、Spirit/VLAGO 25.9%、DM/Embodied AI Institute 23.5%、PI/RoboReasoner 22.8%、GigaBrain/xembody 22.6%、gr00t/Humanoid Dynamics 20.5%），但同页页脚仍写「即将发布」，`leaderboard_data.json` 的 `generated_from` 仍是 `gen_leaderboard.py`，`details.html` 的 32 段视频仍写「测试视频占位，后续可替换为真实视频文件」，`runs.html` 仍是 `256 / 256` 条占位记录。[S3][S4][S5][S6]

**结论：29.7% 不能当作真实成绩，也不能用来判断谁强谁弱。** 但这 8 个模型名对应真实模型家族；把它们的技术报告与 **RoboChallenge Table30 的真实榜单**并置，可以得到一个可信得多的“头部方案解剖”（§1）。用户说的“榜首不到 30%”作为**研究假设**是合理的——它与公开真实参照系同量级——但不能当排名证据。

### 0.2 手册给出了比上一轮更硬的评测算术：10 次/任务 = 5 轴 × 2，成功率优先、步骤分只做 tie-break

中文手册 [S7] / 英文手册 [S8] 明确：

- 每个任务独立跑 **10 次**；10 次中包含 **5 种泛化类型，每种各 2 次**：位置、干扰物、桌面背景、未见物品、人为干扰。
- 32 任务 × 10 次 = **320 个计分 episode**。
- **实时榜单按 32 任务的总平均成功率排序；成功率相同才看总平均步骤分；仍相同则提交早者靠前。**
- 单次任务最长 **180 秒**，超时记失败并按执行情况给步骤分。
- 所有任务必须用**同一个模型**完成，不得按任务混用多个模型；模型类型不限（World Model、VLA 均可）。

这条修正很重要：上一轮把“步骤分占 60%”当成主论据；**步骤分其实只是 tie-break**。放置仍然是 32/32 任务的成功闸门，但理由从“步骤分大头”升级为“**不完成终局放置就没有成功率**”。这意味着：

```text
优先级：成功率 > 步骤分
放置：成功率的闸门（32/32 任务的最后一步都是它或它的变体）
步骤分：仅在成功率打平时决定名次
→ 不应为了多拿部分分而冒“把已成功状态弄坏”的风险；
→ 应把预算集中在“把整条 episode 走完”的鲁棒性上。
```

### 0.3 数据规模与 schema：33k/169h 已全量，但没有物体位姿/分割标签

- 官方口径：32 任务、32,000 演示、169 小时 [S2]；第三方按 32 个 repo 的 `meta/info.json` 统计为 **33,276 集、18,282,246 帧、约 811GB**（许可证以 HF 页面为准）[S20]。
- HangCup：**1,043 集 / 194,564 帧 / 30fps**，`lastModified` 2026-10-14 [S12][S14]；StackBowls：**979 集 / 295,609 帧** [S13]。
- 数据字段只有：四路相机（`head_stereo_left/right` 为**已校正双目**、`wrist_left/right`）、双臂关节/EE 位姿（base 与 torso 两套）、夹爪、下肢/腰、动作流；**没有物体 6D 位姿、没有分割、没有关系标签** [S15]。
- 每条任务在 `meta/tasks.parquet` 里有 5 条英文复述（上轮实测；本轮未重跑，保留为待复核事实）。

**结论：想要 object-centric 的监督，只有三条路——仿真渲染标签、真实自监督（夹爪闭合/运动分割/双目）、少量人工标注。** 这直接决定了本轮“仿真只做标注厂”的定位。

### 0.4 任务规格与泛化备注仍是公开的，且比上一轮更可用

`tasks_v2/<slug>/info.json` 继续给出逐任务 `scoring_points`（满分 100）与 `generalization` 备注（`unseen_object_3`、`human_1_note`、`human_4_note`）。本轮复核了 T01/T07/T10/T27：T27 仍是 30/30/40（放中间→叠第二个→叠第三个），T10 仍是 30/30/40（抓插排→抓插头→插入），T07 仍是 30/30/40（抓→开支架→摆正）[S16][S17][S18][S19]。上一轮的表 A/表 B 继续有效；本轮不再重复 32 行，只在产物区保留聚合与用法。

### 1.2 三条共识

1. **底座形态已经收敛**：VLM/空间 VLM + flow-matching（或 DiT）动作专家，是除 DreamZero（视频扩散 WAM）外的 7 个家族的共同选择。再换一个更大的底座，边际收益在变窄。
2. **数据多样性与本体覆盖是公开基准上的真正分水岭**：WALL-OSS 的 20+ 本体、Spirit 的开放式数据、MolmoAct2 的 720h 双臂，讲的都是同一件事。
3. **显式空间/关系接地正在成为新的差异化**：MolmoAct2 的空间 VLM、DM0 的空间 CoT、GigaBrain 的 RGBD+CoT、DreamZero 的世界模型，方向不同，但都在补“像素→3D 关系”这一层。

### 1.3 三个瓶颈

- **B1 通才干扰**：32 任务、160 条复述、5 轴扰动，单模型共享参数；specialist→generalist 的 25pp 落差是直接证据。模型不是不会做，而是“在错误的任务/错误的物体/错误的步骤上用力”。
- **B2 最后一公里**：插入、堆叠、摆正、拉链、拧盖、倒药——终局步骤同时是成功闸门和最大失败源。上一轮的 P1–P6 继续成立。
- **B3 OOD 场景**：位置/干扰物/背景/未见物品/人为干扰。像素级策略把外观、背景、布局纠缠在一起；换桌布或换一个同类别物体就崩。官方五轴本身就是 OOD 压力的制度化；RoboChallenge 的 generalist 落差（specialist 62.0% → generalist 37.3%）是同一现象的另一面。

### 1.4 对我们意味着什么

**不要再把预算押在“换更大的 VLA”上。** 头部家族的底座已经足够强；UniBot 的 33k 数据也不足以把 14B WAM 或 6B VLA 重新训出质变。真正可叠加的杠杆是：

```text
B1 通才干扰  → 共享的 object-hand-task 关系表示（而不是每任务各自记外观）
B2 最后一公里 → 显式容器/目标/affordance 坐标系 + 落点闭环（上一轮 PGL/OPT/SVL）
B3 OOD 场景  → 关系不变性 + 组合增广 + 轴级诊断（而不是更多像素）
```

三者交集，正好是**场景图（scene graph）**。

## 2. 三个灵感词，各自钉到证据上

### 2.1 仿真训练：从“仿真出策略”降级为“仿真出感知标签”

前几轮已经砍过：自由仿真数据、仿真 RL、运行时仿真/MPC、全 32 任务高保真孪生、WMA-0 进主路径。这些判断本轮不翻案。**但“仿真”不等于“仿真训策略”**。2026 年的 sim2real 感知证据已经足够硬：

- 模块化 sim2real 检测/6D pose 流水线：检测 mAP@50 **0.987**，6D pose 平移误差 **3.54mm**、旋转误差 **1.37°**，接入装配后抓取/装配成功率 **>90%** [S37]。
- 透明物体：单视图体素 occupancy 从仿真直接迁移真机、**无需微调**即可支撑抓取 [S38]；透明 6DoF 仍是难点（HFF6DoF 的 ADD 50.5%），需要专门数据/方法 [S39]；双目透明深度有 ClearDepth 的 sim2real 路线 [S40]。
- 这些工作的共同点：**仿真只负责“像素→几何/类别/位姿”的标签，策略仍在真实数据上训。**

于是本轮把“仿真训练”拆成三种用法，并明确取舍：

| 用法 | 决定 | 理由 |
|---|---|---|
| 仿真训动作策略（RL/IL） | **砍** | sim2real 动作 gap 大；33k 真机数据已够做行为克隆；180s 真机预算不容许 sim 风格的动作 |
| 仿真产感知标签（检测/分割/双目深度/6D pose/affordance/遮挡/关系） | **押** | 标签贵、真实数据无标注；sim2real 感知已有 mAP 0.987/3.54mm 级证据；标签不进入动作策略，规避 sim2real 动作 gap |
| 仿真做评测/诊断（场景组合、轴级压力测试） | **保留** | 只做离线相对比较，不做模型选择；真机调试槽仍是发布门 |

一句话：**Sim2Label, Real2Policy。** 仿真不是“训练场”，是“标注厂”。

### 2.2 目标检测：从“框”升级为“object-hand-task 关系图”

检测本身不是目的。UniBot 的失败不是“没看见杯子”，而是“看见了杯子但不知道哪个是目标、哪个是容器、该从哪抓、该放哪、当前步骤是什么”。2026 年的 scene-graph / relational VLA 证据链正好对齐：

- **UniManip**：object-centric scene graph + agentic operational graph，零样本比 SOTA VLA **+22.5%**、比层级基线 **+25.0%**；还能固定基座→移动操作零样本迁移 [S32]。
- **RoBoSR**：把 scene graph 当**主状态空间**，学习前置条件/效果/目标状态转移；零样本泛化与长程任务优于 prompting 与经典 TAMP [S33]。
- **TriRelVLA**：object–hand–task 三元关系图 + 任务引导 cross-attention + 关系瓶颈；跨场景/跨物体/跨任务均有增益 [S34]。
- **Compose by Focus**：只保留任务相关物体与关系的 scene graph + 图神经网络 + diffusion IL；组合泛化显著优于 SOTA [S35]。
- **iSTAR**：把动态 scene-graph 知识注入 VLA 参数，不引入外部 planner，仍在同一 VLA 参数族内 [S36]。

这些工作的共同结论：**检测的输出不该是 N 个框，而是一个任务条件化的子图**——目标物体、容器/支撑物、夹爪、affordance（抓点/放点/插入轴/开口）、关系（on/in/left-of/stacked-on/inserted/closed）、以及“当前步骤”。框只是节点属性。

对 UniBot 的映射：

```text
语言（160 条复述之一） + SSG 当前步骤
        │
        ▼
任务条件化选择：target object / receptacle / support / 需要忽略的 distractor
        │
        ▼
图节点：物体、容器、夹爪、桌面；边：空间关系 + 功能关系 + 任务约束
        │
        ├─→ PGL：槽位/区域 → 2D 锚点 → 6D 位姿
        ├─→ OPT：容器系释放位姿迁移
        ├─→ ICR：关系中心检索键
        └─→ SVL：落点稳定性/谓词校验
```

### 2.3 场景泛化：从“换背景”升级为“表示不变性 + 组合增广 + 轴级诊断”

五个泛化轴不是五个独立的数据集，而是同一能力的五个压力面：

| 轴 | 像素级策略的失败机制 | 场景图的对应不变量 |
|---|---|---|
| 位置 | 记住绝对坐标/画面位置 | 物体相对容器/桌面的关系与容器系位姿 |
| 干扰物 | 把无关物体当目标 | 任务条件化子图，distractor 降权 |
| 背景 | 把桌布纹理当上下文 | 物体中心节点，背景不入图 |
| 未见物品 | 记住实例外观 | 类别级节点 + affordance，而非实例 ID |
| 人为干扰 | 假设世界静止 | 图随时间更新 + SSG 步骤回退 + NRB 恢复 |

所以“场景泛化”的第一性不是“更多背景图”，而是**让策略看到与背景/位置/实例外观无关的量**。场景图是这种量的载体；组合增广（背景替换、位置平移、干扰物插入、未见物体替换）只是让这个载体见到更多分布；轴级诊断则是用来确认“到底是哪一轴在漏”。

**本轮的一个新评估视角**：不要只报“总成功率”，要报**每个轴的图准确率**（检测/位姿/关系/步骤）。如果背景轴掉 20pp 而位置轴不掉，说明检测器在记纹理；如果未见物品轴掉，说明类别级 affordance 没学会；如果人为干扰轴掉，说明图更新/恢复没做好。**这张“轴 × 图组件”热力图，比总榜更能指导下一轮。**

## 3. 本轮主判断：SGG-PILOT

### 3.1 为什么是场景图，而不是更大的 VLA

把三个瓶颈与三个灵感词对齐：

```text
B1 通才干扰 ── 共享 object-hand-task 图 ── 目标检测（关系化）
B2 最后一公里 ── 容器/目标/affordance 坐标系 ── 场景泛化（相对表示）
B3 OOD 场景 ── 关系不变性 + 组合增广 ── 仿真标注（Sim2Label）
```

场景图同时是：

1. **通才共享接口**：32 个任务共享同一套节点/边/affordance schema，减少“每任务各自记外观”的干扰；
2. **放置的坐标系**：PGL/OPT/SVL 都需要“容器在哪、开口朝哪、放点在哪、插入轴朝哪”，这正是图的边/属性；
3. **OOD 的不变量**：关系与容器系位姿对背景/绝对位置不敏感；类别级 affordance 对未见实例更稳；
4. **诊断的探针**：每个轴的图准确率直接告诉我们哪一层漏；
5. **检索的键**：ICR 从“全局外观相似”升级为“关系+运动相似”，背景轴不再拖垮检索。

### 3.2 与上一轮 PILOT-GPR 的关系：补感知接口，不改主武器

| 关系 | 内容 |
|---|---|
| **保留** | SSG 评分步骤图、PGL 放置目标阶梯、OPT 少样本位姿迁移、ICR 检索、SVL 落点闭环、NRB 官方备注恢复、L2L 实验室协议、DebugLoop、GPR-VLA/WLA 底座 |
| **升级** | PGL/OPT 从“检测容器 + 估位姿”升级为“图节点/边/容器系”；TLE 从“全任务密集标签”升级为 **Sim2Label**（只产感知标签）；ICR 键从“关键点+光流”升级为 **Graph-ICR**（关系+相位+运动）；TCLB 降级为离线比较，主回路改为 **轴级图诊断 + 调试槽** |
| **新增** | **SGG**（object-hand-task 场景图）、**Sim2Label**（仿真感知标注厂）、**Graph-ICR**、**Axis-Graph**（轴级图诊断）、**SGG-Lite**（冻结 VLA + 外部检测器的两周最小版）、**OCWM**（object-centric world model critic，P2 可选） |
| **修剪** | 独立 SAM/FoundationPose 作为推理主路径（折进单模型辅助头或只做离线标注）；全 32 任务高保真孪生（砍到 14 个 A 类 + 12 个 B 类 + 6 个 C 类轻量）；世界模型当策略（只保留 critic）；每任务 LoRA（改为图/技能条件化）；“步骤分优先”的预算逻辑（改为成功率优先） |

### 3.3 两条落地路线：SGG-Lite 与 SGG-Full

**SGG-Lite（W1–W3，最小可运行）**

```text
冻结的强 VLA（WLA-1.0-Base / MolmoAct2 / WALL-OSS 任一）
  + 现成检测器/分割器（YOLO-World/SAM2，共享、非任务特定）
  + 双目深度（若高位相机确为双目）或单目深度
  + 规则几何 → 场景图
  + 图渲染成 overlay / 文本，喂给冻结 VLA
  + PGL/OPT/SVL 用图坐标
```

优点：不重训、两周可出结果、可立刻在调试槽验证“图有没有用”。缺点：外部检测器是第二个模型，单模型合规有风险；透明/小物体检测可能不稳。**合规定位：只作为离线/调试版，或把检测器声明为“全任务共享的感知前端”并在模型卡披露；正式提交优先 SGG-Full。**

**SGG-Full（W4–W7，正式版）**

```text
单一 VLA checkpoint（共享视觉编码器）
  ├─ 动作专家（真实 33k 训练，flow matching）
  ├─ 辅助头 1：任务条件化检测/分割（sim 标签 + 真实自监督）
  ├─ 辅助头 2：双目深度/occupancy（sim 标签；透明物体专用）
  ├─ 辅助头 3：6D 位姿/关键点（仅刚体；透明用 occupancy）
  ├─ 辅助头 4：affordance（抓点/放点/插入轴/开口）
  ├─ 辅助头 5：关系/步骤谓词（SSG）
  └─ 图 adapter（2–4 层 graph transformer → cross-attention tokens）
```

优点：真正单模型；辅助头与动作专家共享视觉特征；图在训练时同步注入，推理时不崩。缺点：工程量大；需要 sim 资产与真实自监督标签；8 周紧张。

### 3.4 可证伪的收益算术

- 32 任务 × 10 次 = 320 个计分 episode；p≈0.3 时二项标准误 ≈ **2.56pp**。+5pp ≈ 2σ，+3pp ≈ 1.2σ。**目标定 +5pp 成功率**，而不是 +3pp 的噪声级。
- 若 SGG 让“到达终局步的通过率 q”从 0.5–0.7 提升，且终局放置成功率 +Δ，则全局成功率约 +Δ×q；同时 B1/B3 的改善会抬高 q 本身。**这是乘性收益，不是加性。**
- 可证伪点：
  1. 离线图准确率（检测 mAP@0.5、位姿 ADD、关系 F1）在 A 类任务上达不到阈值 → 图不可用，回退 PGL/OPT 的纯几何版；
  2. 调试槽里 T27 或 T10（单任务）的终局步成功率提升 <5pp → SGG 假设不成立，回退 SSG+SVL；
  3. 延迟 p99 >100ms → 降频/降 K/关图 adapter，只保留 overlay。
- 统计上，320 trials 的 +5pp 是 2σ；如果只做 1 个调试槽的 10 次单任务，噪声极大，**调试槽只做“方向性 Go/No-Go”，不做显著性结论**。

## 5. 风险与合规（先立后破）

- **单模型定义**：手册只禁止“按任务混用多个模型”，未明确禁止共享感知模块；但正式提交优先把检测/深度/pose 折进同一 checkpoint 的辅助头。若用外部检测器，必须在模型卡披露“全任务共享、非任务特定”，并准备回退到纯 VLA。
- **外部数据/预训练权重**：手册前两章未明确；默认只用官方 33k + 自生成仿真标签；公开预训练权重按“模型类型不限”推断可用，但邮件 `challenge_support@unitree.com` 确认前不把外部实验室数据并入训练。`external_lab_data: false` 默认。
- **仿真资产许可**：优先程序化资产 + 官方 sim 资产；Objaverse/ShapeNet 逐个核许可；不用来源不明的 CAD。
- **透明/布料/小件**：不强行 6D pose；透明走双目/occupancy，布料走 2D keypoint/affordance，小件走腕部高分辨 crop。
- **图错误传播**：图是软先验，不是硬约束；训练时随机 dropout 图 token/overlay；低置信度节点 mask；图错时回退 image-only。
- **延迟**：双目+检测+pose+图+VLA 的 p99 必须 <100ms；感知 5–10Hz、动作 chunk 8–16、缓存；超时降频/降 K/关图。
- **统计噪声**：320 trials 的 +5pp 才是 2σ；不要用单任务 10 次调试槽下强结论。
- **时间**：SGG-Lite 两周可出方向性结果；SGG-Full 需要 4–6 周；若 W3 图准确率不达标，立即回退上一轮 PGL/OPT。

## 6. 本轮修剪清单（明确不做什么）

- **砍**：仿真训动作策略/RL；全 32 任务高保真孪生；独立 SAM/FoundationPose 作为推理主路径；每任务 LoRA；世界模型当策略；步骤分优先的预算逻辑；自由仿真数据。
- **保留**：SSG、PGL、OPT、ICR、SVL、NRB、L2L、DebugLoop、GPR-VLA/WLA。
- **升级**：TLE→Sim2Label；PGL/OPT→图坐标系；ICR→Graph-ICR；TCLB→轴级图诊断。
- **新增**：SGG、Sim2Label、Graph-ICR、Axis-Graph、SGG-Lite、OCWM（P2）。

## 7. 一句话押注

**把场景图做成通才模型的眼睛：用仿真只产感知标签（检测/双目深度/6D pose/affordance），在单一 VLA 内训练 object-hand-task 关系图，再用这张图同时驱动放置（PGL/OPT/SVL）、检索（ICR）和五轴诊断——这比再换一个更大的 VLA 更可能把 30% 的天花板抬起来。**

### 2.2 三条共识

1. **底座形态已收敛**：VLM/空间 VLM + flow-matching（或 DiT）动作专家，是除 DreamZero（视频扩散 WAM）外的 7 个家族的共同选择。再换更大的底座，边际收益在变窄。
2. **数据多样性与本体覆盖是公开基准上的真正分水岭**：WALL-OSS 的 20+ 本体、Spirit 的开放式数据、MolmoAct2 的 720h 双臂，讲的都是同一件事。
3. **显式空间/关系接地正在成为新的差异化**：MolmoAct2 的空间 VLM、DM0 的空间 CoT、GigaBrain 的 RGBD+CoT、DreamZero 的世界模型，方向不同，但都在补“像素→3D 关系”这一层。

### 2.3 三个瓶颈

- **B1 通才干扰**：32 任务、160 条复述、5 轴扰动，单模型共享参数；specialist→generalist 的 25pp 落差是直接证据。模型不是不会做，而是“在错误的任务/错误的物体/错误的步骤上用力”。
- **B2 最后一公里**：插入、堆叠、摆正、拉链、拧盖、倒药——终局步骤同时是成功闸门和最大失败源。上一轮的 P1–P6 继续成立。
- **B3 OOD 场景**：位置/干扰物/背景/未见物品/人为干扰。像素级策略把外观、背景、布局纠缠在一起；换桌布或换一个同类别物体就崩。官方五轴本身就是 OOD 压力的制度化；RoboChallenge 的 generalist 落差（specialist 62.0% → generalist 37.3%）是同一现象的另一面。

### 2.4 对我们意味着什么

**不要再把预算押在“换更大的 VLA”上。** 头部家族的底座已经足够强；UniBot 的 33k 数据也不足以把 14B WAM 或 6B VLA 重新训出质变。真正可叠加的杠杆是：

```text
B1 通才干扰  → 共享的 object-hand-task 关系表示（而不是每任务各自记外观）
B2 最后一公里 → 显式容器/目标/affordance 坐标系 + 落点闭环（上一轮 PGL/OPT/SVL）
B3 OOD 场景  → 关系不变性 + 组合增广 + 轴级诊断（而不是更多像素）
```

三者交集，正好是**场景图（scene graph）**。

## 3. 问题定义：为什么 30% 的天花板是“通才 + 最后一公里 + OOD”

### 3.1 成功率优先的算术

```text
成功率 = P(所有步骤完成)              # 32/32 任务的闸门都是终局步骤
步骤分 = Σ 步骤权重 × P(该步完成)     # 放置类 ≈59.7%，终局 ≈39.8%
排名   = 总平均成功率 → 总平均步骤分 → 提交时间
```

- 320 个计分 episode；p≈0.3 时 SE≈2.56pp；+5pp≈2σ，+3pp≈1.2σ。
- 调试槽单任务 10 次，单任务 SE≈14.5pp；**只能做方向性 Go/No-Go，不能做显著性结论**。
- 部分分 farming 的价值下降：为了多拿 20–30 步骤分而把已成功状态弄坏，可能从“成功”变成“失败”，在成功率优先下不划算。
- 放置是 32/32 任务的终局闸门；SVL 的“缓放+校验+微调”比“快速冲过去”更符合评分规则。

### 3.2 specialist–generalist gap 的机制

RoboChallenge 的 25pp 落差不是“技能不会”，而是三个共享参数冲突：

1. **任务条件冲突**：32 个任务共享同一动作专家，语言/视觉条件不足时，模型把 A 任务的抓取/放置习惯带到 B 任务。
2. **物体/容器冲突**：相似外观的物体在不同任务里角色不同（杯子在 T01 要挂、在 T25 要放架），纯外观表示无法区分“角色”。
3. **步骤冲突**：同一物体在不同步骤的 affordance 不同（先抓杯柄，后挂杯柄），没有步骤条件就会“抓了但不知道下一步”。

场景图的节点角色（target/receptacle/support/distractor）+ 边（graspable_by/insertable_into/stackable_on）+ 步骤条件，正好把这三个冲突显式化。

### 3.3 失败模式表（P1–P6 + G1–G3）

| 编号 | 失败模式 | 典型任务 | 现有组件 | 本轮补法 |
|---|---|---|---|---|

### 4.2 场景图 schema

#### 4.2.1 节点

| 类型 | 字段 | 说明 |
|---|---|---|
| `robot` | `base_pose`, `torso_pose`, `left/right_gripper_pose`, `gripper_state` | 手物关系、可达性、碰撞 |
| `object` | `category`, `pose6d`, `bbox3d`, `mask2d`, `state`, `affordance`, `conf` | 任务物体/工具/小件 |
| `container` | `pose6d`, `opening_normal`, `interior_frame`, `capacity`, `state` | 杯/碗/盒/架/插排/试管架 |
| `support` | `plane`, `normal`, `region` | 桌面/架子/传送带 |
| `distractor` | `category`, `pose6d`, `conf`, `ignore_reason` | 非任务物体；降权 |
| `human` | `hand_pose`, `arm_pose`, `conf` | 人为干扰轴；可选 |

#### 4.2.2 边

| 类别 | 边 | 用途 |
|---|---|---|
| 空间 | `left_of`, `right_of`, `front_of`, `behind`, `above`, `below`, `on`, `in`, `near` | 关系不变性；PGL 槽位 |
| 功能 | `graspable_by`, `insertable_into`, `stackable_on`, `contained_in`, `aligned_with`, `occludes`, `supports` | affordance/放置/插入 |
| 任务 | `target_of`, `receptacle_for`, `next_step`, `must_avoid`, `must_preserve` | SSG 步骤条件 |
| 时序 | `before`, `after`, `during` | 长程/恢复 |

#### 4.2.3 任务条件化子图

不是整张场景图，而是“当前步骤相关的子图”：

```text
输入：task_id, step s_t, language, 全图 G
选择：target(s) ∪ receptacle(s) ∪ support ∪ 必要 distractor ∪ 双夹爪
裁剪：与 target 距离 > r 的节点；与当前步骤无关的边
输出：G_t（节点 ≤12，边 ≤24，token ≤16）
```

这直接对应 B1 通才干扰：32 个任务共享 schema，但每步只看相关子图；distractor 显式标 `ignore_reason`，而不是靠模型自己忽略。

### 4.3 感知头

| 头 | 输出 | 训练标签 | 透明/布料处理 | 推理频率 |
|---|---|---|---|---|
| 检测 | 2D box + mask + 3D centroid + category + conf | Sim2Label 检测/分割；真实自监督 mask | 透明用双目/occupancy 补；布料用 2D keypoint | 5–10Hz |
| 双目深度 | disparity/depth + confidence | Sim 双目 + 真实光度一致性 | ClearDepth/Trans2Occ 路线 | 5–10Hz |
| occupancy | 体素/TSDF（透明/小件） | Sim 体素标签 | 单视图 occupancy 零微调迁移 [S38] | 5Hz |
| 6D pose | R,t + ADD 置信度 | Sim CAD pose；刚体 | 透明不强行 6D；用容器系/occupancy | 5–10Hz |
| affordance | 抓点热图、接近向量、放点热图、插入轴、开口法向 | Sim affordance + 真实夹爪闭合点 | 布料用 2D keypoint；透明用开口/杯沿 | 5–10Hz |
| 关系 | 边标签 + conf | 几何规则 + sim 关系标签 + 人工 QA | 同左 | 图更新时 |
| 步骤谓词 | 步骤完成概率 | SSG + 真实相位 + sim | 同左 | 每步 |

**关键设计**：所有头共享 VLA 的视觉编码器（或共享一个轻量视觉塔），**不引入第二个独立大模型**；透明/布料/小件不追求统一 6D pose，而是“能抓到/能放对”的任务相关表示。

### 4.4 图条件化 VLA

三种注入方式，按周次渐进：

| 方式 | 做法 | 优点 | 缺点 | 用在哪 |
|---|---|---|---|---|
| **Overlay** | 把框/掩码/抓点/放点/插入轴/关系箭头渲染到图像上 | 零架构改动；任何 VLA 可用 | 视觉杂乱；遮挡；域差 | SGG-Lite W1–W3 |
| **Text** | 把子图序列化成紧凑文本，追加到语言指令 | 零架构；可解释 | 提示变长；精度有限 | SGG-Lite W1–W3 |
| **Tokens** | 图 adapter（2–4 层 graph transformer）→ K 个 token → cross-attention | 表达力强；干净 | 架构/审计；需训练 | SGG-Full W4–W7 |

**鲁棒性**：

- 训练时 **graph dropout 10–20%**：随机把图 token/overlay 置零，让 VLA 保留 image-only 回退能力。
- **置信度加权**：节点/边 conf < τ 时 mask；不让错误图硬控动作。
- **图过期检测**：物体位姿变化 >2cm 或夹爪状态变化 → 重建子图；否则缓存。
- **冲突仲裁**：图与图像冲突时，以图像为主、图为软先验；PGL/OPT 只在图 conf 足够高时启用。

### 4.5 与 SSG/PGL/OPT/ICR/SVL/NRB 的接口

| 组件 | 输入 | 图提供什么 | 输出 |
|---|---|---|---|
| SSG | language, step | 任务条件化子图模板；步骤谓词 | `task_id`, `s_t`, `predicate` |
| PGL | `s_t`, 子图 | target/receptacle 节点、place affordance、容器系 | 2D 锚点→6D 位姿目标 |
| OPT | `s_t`, 容器节点 | 容器 pose/frame；H_i 坐标系 | 当前场景释放位姿 |
| Graph-ICR | `s_t`, 子图 | 关系签名、相位、运动键 | K 条上下文/动作先验 |
| SVL | 目标位姿、图谓词 | 落点区域、稳定性谓词、must_preserve | nudge/regrasp/retry |
| NRB | 谓词 1→0 | 图更新、被撤销对象、回退步骤 | 恢复动作/重试 |

### 4.6 单模型合规设计

- **一个 checkpoint**：动作专家 + 辅助头 + 图 adapter 全在一个模型里；共享视觉编码器；无按任务路由的权重。
- **确定性代码**：SSG/PGL/SVL/几何关系是规则代码，不是“第二个模型”；不违反“单模型”精神。
- **外部检测器**：只在 SGG-Lite 调试版使用；正式提交优先辅助头。若必须用，声明“全任务共享的感知前端、非任务特定”，并在模型卡披露。
- **模型卡**：列出所有组件、训练数据（官方 33k、仿真标签、是否外部权重）、许可证、推理图；无隐藏任务模型。
- **审计开关**：`sgg_mode=off` 可一键回退纯 VLA；`external_detector=false` 可关闭外部前端。

## 5. Sim2Label 数据引擎

### 5.1 为什么仿真只做感知

| 用法 | 决定 | 理由 |
|---|---|---|
| 仿真训动作策略（RL/IL） | **砍** | sim2real 动作 gap 大；33k 真机数据已够行为克隆；180s 真机预算不容许 sim 风格动作 |
| 仿真产感知标签 | **押** | 标签贵、真实数据无标注；sim2real 感知已有 mAP 0.987/3.54mm 级证据；标签不进入动作策略，规避动作 gap |
| 仿真做评测/诊断 | **保留** | 只做离线相对比较；真机调试槽仍是发布门 |

一句话：**Sim2Label, Real2Policy。**

### 5.2 任务分桶与渲染量

| 桶 | 任务 | 数量 | 每任务场景×帧 | 帧数 | 标签重点 |
|---|---|---:|---|---:|---|
| A 不透明/半刚体放置 | T01/T02/T03/T04/T06/T08/T13/T15/T20/T21/T22/T25/T27/T30 | 14 | 100×20 | 28,000 | 检测/分割/6D pose/放点/关系 |
| B 铰接/插入 | T05/T07/T09/T10/T12/T18/T19/T23/T26/T28/T29/T31 | 12 | 80×20 | 19,200 | 关键点/插入轴/开口/铰接状态 |
| C 透明/布料/小件 | T11/T14/T16/T17/T24/T32 | 6 | 60×20 | 7,200 | 双目/occupancy/2D keypoint/affordance |
| **合计** | 32 | 32 | — | **54,400 帧 × 4 相机 = 217,600 图** | — |

**说明**：A/B/C 是感知难度分桶，不是动作策略分桶；同一 VLA 仍处理全部 32 任务。C 桶不追求 6D pose，只追求“抓得到/放得对”的表示。

### 5.4 域随机化

- **光照**：色温、强度、方向、阴影；避免过暗/过曝。
- **背景**：桌布颜色/纹理/图案；与官方 5 轴背景分布对齐；每任务 ≥20 种。
- **相机**：高位/腕部外参微扰、焦距、曝光、噪声、运动模糊。
- **物体**：位姿、尺度 ±10%、颜色/材质、同类替换（未见物品轴）。
- **干扰物**：官方 distractor 类别 + 随机桌面杂物；遮挡关系。
- **透明/布料**：折射/反射/厚度；布料褶皱/材质；小件高分辨 crop。
- **人手/人臂**：随机进入画面、移动物体、遮挡；对应 human 轴。
- **传送带**：速度/相位/物体位置（T24）。

### 5.5 真实自监督标签

| 标签 | 方法 | 数据量 | 备注 |
|---|---|---|---|
| 抓点 | 夹爪闭合瞬间的 EE 位置投影到图像；SAM2 point prompt | 33k episodes 采样 20% | 夹爪闭合检测用 gripper 状态 |
| 物体 mask | 运动分割 + SAM2 视频跟踪 | 6,655 episodes × 10 帧 | 夹爪/手臂 mask 剔除 |
| 深度 | 高位双目立体匹配；光度一致性 | 全部帧可离线算 | 透明区域低置信度 |
| 手物关系 | EE pose + 物体 mask/点云 | 同上 | 接触/接近/抓取 |
| 相位/步骤 | 动作速度/夹爪/EE 轨迹 + SSG | 全部 episodes | 伪标签 + 人工 QA |
| 语言 | 官方 5 复述 | 32×5 | 指令-图对齐 |

**人工 QA**：32 任务 × 150 帧 = 4,800 帧；2 名标注员；3–5 天；只校关系/步骤/affordance，不重画所有 mask。

### 5.6 数据量与算力

| 项 | 估算 |
|---|---|
| 仿真渲染 | 54,400 帧 × 4 相机，512×512；8×H100，约 2 天（光栅化+随机化） |
| 感知预训练 | 8×H100，约 3 天 |
| VLA 动作微调 | 8×H100，约 2 周（LoRA + 辅助头） |

| 存储 | 官方数据 811GB + 仿真标签 1–2TB |
| 最小版 | 1×H100/A100 可跑 SGG-Lite（冻结 VLA + 检测器） |

### 5.7 QA 与许可

- 仿真资产优先程序化 + 官方 sim 资产 [S41]；Objaverse/ShapeNet 逐个核许可；不用来源不明 CAD。
- 透明/布料资产单独核许可；不把受限资产烘进发布 checkpoint。
- 标签格式统一（COCO/自定义 JSONL）；每帧记录 seed/场景/相机/标签版本。

### 6.2 损失

```text
L = 1.0 * L_action          # flow matching / velocity MSE
  + 0.2 * L_det             # focal + GIoU
  + 0.1 * L_seg             # dice + BCE
  + 0.2 * L_depth           # L1 + gradient
  + 0.2 * L_pose            # ADD-S + keypoint
  + 0.2 * L_affordance      # heatmap BCE/MSE
  + 0.1 * L_relation        # BCE
  + 0.1 * L_step            # BCE
  + 0.05 * L_consistency    # affordance 与动作终点的一致性（可选）
```

权重按验证集调；动作损失不能被辅助损失压过（监控 action val loss）。

### 6.3 超参

| 项 | 建议 |
|---|---|
| 底座 | WLA-1.0-Base（许可证以模型卡为准）[S43][S44]；对比 MolmoAct2/WALL-OSS/Spirit |
| 微调 | LoRA r=32–64，alpha=64；aux heads 全参 |
| 图像 | VLA 448×448；aux 256×256；腕部 crop 224×224 |
| chunk | 8–16；推理 10–15Hz |
| batch | 64（梯度累积可调） |
| LR | LoRA 1e-4；aux 1e-5；cosine |
| 精度 | bf16；推理 FP16/INT8 |
| 步数 | 100k–200k；早停看 action val + 图 val |
| 并行 | FSDP/DeepSpeed；8×H100 |

### 6.4 数据混合与课程

- 任务平衡：32 任务等权；难任务（T09/T10/T12/T16/T28/T29）过采样 2×。
- 轴平衡：每个任务尽量覆盖 5 轴；不足的用合成编辑/仿真补。
- 课程：先 A 桶（刚体放置）→ B 桶（插入/铰接）→ C 桶（透明/布料/小件）；图 adapter 先在 A 桶训，再全任务。
- 语言：5 复述 + 中文映射 + 未见复述（留出 10% 做泛化测试）。
- 图 dropout：10–20%；低置信度节点 mask 概率 10%。

### 6.5 延迟优化

- TensorRT/ONNX 导出；FP16；aux heads 5Hz；VLA 10–15Hz；chunk 16。
- 图 token 上限 16；节点上限 12；边上限 24。
- 双目/检测/pose 异步流水线；缓存上一帧图；只在物体变化 >2cm 或夹爪状态变化时重建。
- 腕部 crop 只在高位检测不确定时启用；透明/小件优先腕部。

## 7. 推理与接口工程

### 7.1 延迟预算（目标 p99 <100ms）

| 模块 | 延迟（ms） | 频率 | 备注 |
|---|---:|---|---|
| 双目匹配 | 10–15 | 5–10Hz | 320×240；TensorRT |
| 检测 | 8–12 | 5–10Hz | YOLO-World-S/RT-DETR |
| 分割 | 10–15 | 5Hz | SAM2-tiny/mobile；可异步 |
| 6D pose | 3–10 | 5–10Hz | keypoint PnP + refinement |
| occupancy | 10–15 | 5Hz | 透明/小件；可异步 |
| 图构建/更新 | 1–2 | 变化时 | CPU/GPU |
| 图 adapter | 3–5 | 10Hz | 2–4 层 |
| VLA | 30–50 | 10–15Hz | 2–4B，FP16，chunk 16 |
| SVL | 2–5 | 每步 | 控制循环 |
| **合计** | **60–100** | — | 异步后 p99 可控 |

### 7.2 缓存与频率

- 感知 5–10Hz；VLA 10–15Hz；动作 chunk 8–16；SVL 每步。
- 图缓存：物体位姿变化 <2cm 且夹爪状态不变 → 复用；否则重建。
- ICR 缓存：同一任务/步骤的 K 条上下文编码缓存；换任务清空。
- 多端口：每端口独立进程/状态；`reset()` 清图/缓存/ICR；不共享可变状态。

### 7.3 置信度门控与回退

```text
if graph_conf < τ_graph:
    use image-only VLA + PGL/OPT 几何回退
elif stereo_conf < τ_depth:
    use monocular depth / wrist crop
elif detector_conf < τ_det:
    use geometric container prior + SVL
else:
    full SGG
```

- `τ_graph` 按验证集调；默认 0.6。
- 图与图像冲突：图像优先；图只做软先验。
- 检测失败：用上一帧图 + EE 运动外推；SVL 兜底。
- 超时：降频/降 K/关图 adapter；保底纯 VLA。

### 7.4 控制空间

- **EE 空间**：推荐用于放置/插入/堆叠（PGL/OPT/SVL 直接给 EE 目标）；跨本体更稳。
- **Joint 空间**：用于需要腰/全身协调/碰撞规避的任务；但放置精度更难。
- 建议：先 EE 全任务；对 T16/T17/T31 等长程/布料任务做 joint 对照；提交只能选一个，按验证集定。

### 7.5 多端口/状态隔离（FLEET 检查单）

- 每个端口一个进程；`reset()` 清空图/缓存/ICR/历史动作。
- token 双处校验；不在日志打印 token。
- 端口数 = N；从 8765 连续；启动时握手。
- 异常：单端口崩溃不影响其他端口；看门狗重启；记录 episode id。
- 延迟/显存监控；超过阈值自动降级。

## 8. 评测协议

### 8.1 三级评测

| 级别 | 内容 | 样本 | 用途 |
|---|---|---|---|
| L1 离线 | 检测 mAP/mask IoU/depth RMSE/pose ADD/affordance recall/relation F1/step acc | 验证集 | 图是否可用 |
| L2 调试槽 | 单任务 10 次；终局步成功率/延迟/失败视频 | 1 任务 | 方向性 Go/No-Go |
| L3 正式 | 32 任务 ×10；成功率/步骤分 | 320 | 排名 |

### 8.2 轴级图诊断（Axis-Graph）

行 = 5 轴（位置/干扰物/背景/未见物品/人为干扰）；列 = 图组件（检测/深度/pose/关系/步骤/动作）；值 = 相对 ID 的准确率下降（pp）。

| 轴 \ 组件 | 检测 | 深度 | pose | 关系 | 步骤 | 动作 |
|---|---:|---:|---:|---:|---:|---:|
| 位置 |  |  |  |  |  |  |
| 干扰物 |  |  |  |  |  |  |
| 背景 |  |  |  |  |  |  |
| 未见物品 |  |  |  |  |  |  |
| 人为干扰 |  |  |  |  |  |  |

**解读**：

- 背景轴检测掉、关系不掉 → 检测器记纹理；加背景随机化/分割归一化。
- 未见物品轴检测掉 → 类别级表示不足；加同类替换/开放词表。
- 人为干扰轴步骤掉 → 图更新/回退不足；加 NRB/图跟踪。
- 位置轴 pose 掉 → 绝对坐标依赖；改容器系/相对表示。
- 干扰物轴关系掉 → 任务条件化不足；加 distractor 降权/子图裁剪。

### 8.3 统计功效

- 320 trials；p≈0.3 时 SE≈2.56pp；+5pp≈2σ；+3pp≈1.2σ。
- 每任务 10 次，单任务 SE≈14.5pp；不要用单任务下强结论。
- 配对 bootstrap（按任务重采样）给 95% CI；报告成功率/步骤分/延迟。
- 多轴比较做 Bonferroni/FDR 校正；避免“挑一个轴显著”讲故事。

### 8.4 Go/No-Go

| 节点 | 指标 | 阈值 | 不达标动作 |
|---|---|---|---|
| W3 | A 桶检测 mAP@0.5；pose ADD；关系 F1 | ≥0.8；≤10mm；≥0.75 | 回退 PGL/OPT 纯几何 |
| W3 | 延迟 p99 | <100ms | 降频/降 K/关 adapter |
| W5 | 调试槽（T27 或 T10，单任务）终局步 | +10pp | 回退 SSG+SVL |
| W7 | 正式/验证全局成功率 | +3pp | 保基线，提交保守版 |
| W7 | 轴级诊断 | 至少 2 轴改善 | 只保留有效组件 |

### 10.1 核心点展开

#### I14 SGG：object-hand-task 场景图

- **动机**：通才干扰（B1）+ 最后一公里（B2）+ OOD（B3）共享一个缺失层——任务条件化的物体/手/关系表示。
- **与现有工作的差异**：UniManip/RoBoSR/TriRelVLA 主要在各自基准/桌面场景验证；本方案把图折进**单一 VLA 的辅助头**，不引入外部 planner，且用官方 33k + Sim2Label 训练；图的角色是“软先验 + 放置坐标系 + 诊断探针”，不是硬约束。
- **可行性**：A 桶刚体检测/pose 有 sim2real 证据；C 桶透明/布料用双目/occupancy/2D keypoint 绕开 6D；图 adapter 2–4 层，参数 <5% 底座。
- **资源**：8×H100；Sim2Label 2 天渲染；感知 3 天；VLA 2 周。
- **步骤**：schema → sim 标签 → 辅助头 → 图 adapter → 调试槽 → 全量。
- **风险**：图错传播；用 dropout/置信度/回退缓解；检测器域差；用真实自监督/背景随机化缓解。

#### I15 Sim2Label：仿真标注厂

- **动机**：33k 真机无物体标签；人工标注 32 任务不可扩展；仿真标签便宜且不进入动作策略。
- **差异**：不是“仿真训策略”，也不是“全任务数字孪生”；只渲染感知相关场景，标签覆盖检测/分割/双目/occupancy/pose/affordance/关系。
- **可行性**：检测 mAP 0.987、pose 3.54mm/1.37°、抓取>90% [S37]；Trans2Occ 透明 occupancy 零微调 [S38]。
- **资源**：54.4k 帧 ×4 相机；2 天渲染；1–2TB 存储。
- **步骤**：A 桶 → B 桶 → C 桶；先刚体，后透明/布料。
- **风险**：sim2real 外观差；域随机化 + 真实自监督 + 少量人工 QA；资产许可逐个核。

#### I16 Graph-ICR：关系检索

- **动机**：上一轮 ICR 用关键点+光流，背景/位置轴会污染相似度；关系图提供更稳的键。
- **差异**：键 =（task, step, 关系签名, 相位, 运动）；检索的是“关系相似”的上下文，不是“外观相似”。
- **可行性**：33k episodes 足够建库；图检索是 CPU/GPU 最近邻，无梯度。
- **资源**：离线建库 1 天；推理 <2ms。
- **步骤**：图签名 → 检索 → 动作先验 → 与 VLA 融合。
- **风险**：图签名过粗/过细；用验证集调；保留外观键做 fallback。

#### I17 Axis-Graph：轴级诊断

- **动机**：总榜只告诉“差”，不告诉“哪一层差”；五轴 × 图组件能定位。
- **差异**：不是再跑一个 benchmark，而是把官方 5 轴与图组件交叉，形成可执行的诊断矩阵。
- **可行性**：离线可用仿真/合成编辑；真机调试槽抽检。
- **资源**：离线 2–3 天；调试槽 1 次。
- **步骤**：定义指标 → 跑轴 → 出热力图 → 排下一轮优先级。
- **风险**：仿真轴与真机轴不一致；只做相对比较，不做绝对结论。

#### I18 OCWM：对象中心世界模型 critic（P2）

- **动机**：DreamZero 证明世界模型泛化强，但 14B/7Hz 不适合 UniBot 的 180s/单模型/33k 约束；用图做低维状态，保留“预测后果”的好处。
- **差异**：不是视频 WAM，而是 object-centric graph world model；输入 G_t + 动作，预测 G_{t+1}/成功/稳定性；只做 critic，不做策略。
- **可行性**：图状态维度低；33k + sim 可训；推理 <5ms。
- **资源**：8×H100 3–5 天；P2，不影响主线。
- **步骤**：图转移数据 → 训练 → 给 SVL/ICR 打分 → 消融。
- **风险**：图误差累积；只在短程（1–2 步）预测；不作为唯一决策依据。

#### I19 SGG-Lite：两周最小版

- **动机**：在投入 SGG-Full 前，先用冻结 VLA + 现成检测器验证“图有没有用”。
- **差异**：不改模型；overlay/文本注入；只跑 4 个任务（T27/T10/T07/T19）。
- **可行性**：1×H100 可跑；检测器现成；图规则代码 1 周。
- **资源**：2 周；1–2 人。
- **步骤**：检测 → 图 → overlay → 冻结 VLA → 调试槽。
- **风险**：外部检测器合规；只做调试版；正式提交前折进辅助头。

### 10.2 修剪清单

| 修剪项 | 原因 | 替代 |
|---|---|---|
| 仿真训动作策略/RL | sim2real 动作 gap；33k 真机够 | Sim2Label 只产感知标签 |
| 全 32 任务高保真孪生 | 成本高、收益低 | 14 A + 12 B + 6 C 轻量 |
| 独立 SAM/FoundationPose 推理主路径 | 第二模型、延迟 | 辅助头/离线标注 |
| 每任务 LoRA | 32 套权重、易过拟合 | 图/技能条件化 |
| 世界模型当策略 | 14B/7Hz、33k 不足 | OCWM critic（P2） |
| 步骤分优先的预算 | 规则是成功率优先 | 成功率/终局步优先 |
| 自由仿真数据 | 分布不可控 | Sim2Label 定向渲染 |
| 运行时 MPC/仿真 | 延迟/合规 | 离线 OPT + SVL |

## 11. 风险、合规与开关

| 风险 | 影响 | 缓解 | 开关 |
|---|---|---|---|
| 单模型定义（辅助头/外部检测器） | 合规 | 折进同一 checkpoint；模型卡披露；Lite 只调试 | `external_detector=false` |
| 外部数据/预训练权重未明确 | 合规 | 默认只用官方 33k + 自生成 sim 标签；邮件确认 | `external_lab_data=false` |
| 仿真资产许可 | 发布 | 程序化/官方资产；逐个核许可 | `sim_assets=programmatic` |
| 透明/布料/小件 | 感知 | 双目/occupancy/2D keypoint；不强行 6D | `hard_perception=stereo` |
| 图错传播 | 动作 | graph dropout/置信度/图像优先 | `graph_dropout=0.15` |
| 延迟 | 评测 | 降频/降 K/关 adapter | `sgg_mode=off` |
| 统计噪声 | 结论 | 320 trials/+5pp 2σ；调试槽只做方向 | — |
| 时间 | 交付 | Lite 先行；W3/W5/W7 Go/No-Go | — |
| 多端口状态串扰 | 评测 | 每端口独立进程；reset 清状态 | `fleet_isolation=true` |
| 视频/日志泄漏 token | 安全 | 不打印 token；日志脱敏 | — |

**合规检查单**：

- [ ] 一个 checkpoint；无按任务路由权重。
- [ ] 模型卡列出所有组件/数据/许可证/外部权重。
- [ ] 仿真标签不进入动作策略（只进辅助头）。
- [ ] 外部检测器（若用）全任务共享、非任务特定、已披露。
- [ ] 推理无网络调用（除官方 API）；无隐藏服务。
- [ ] 训练数据只含官方 33k + 自生成 sim + 公开预训练（若确认）。
- [ ] 评测端口/状态隔离；reset 清图/缓存。
- [ ] 延迟/显存监控；降级开关可用。
