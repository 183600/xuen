# 想法区 · 第 4 轮：两种装不下，和一条被定理封死的路

**灵感词**：博弈树搜索 / program analysis / dynamic programming
**起点**：v1.3「X-DUB/PACE*」。38 例（n=12–21）上 5,318 节点 / 0.34 s / 849 表；32 个实例在根部闭合（14 条 INT 证书 + 18 个 DEAD/PACK），剩下 6 例只降到 4.3×。本轮想回答一个很具体的问题：**这 6 例的 gap，是"证书不够强"，还是"证书用错了地方"？**

## 一、先纠正 v1.3 的一个命名错误：INT 不是"能量松弛"

v1.3 把

```text
α_i(a,b) = max(0, min(p_i, b−a, r_i+p_i−a, b−d_i+p_i))
```

叫作"强制工作量 / 能量"，并把它解释成"抢占式松弛"。严格说，这个名字是错的。α 是**非抢占**的强制工作量：它假设任务 i 必须作为一个连续块 `[s,s+p_i]` 执行，再在所有可行起点里取与区间重叠的最小值。

一个反例就够了：`r=0, d=10, p=5, [a,b]=[4,6]`。

```text
α = min(5, 2, 0+5−4, 6−10+5) = 1
e = max(0, p − (d−r) + |[a,b]∩[r,d]|) = max(0, 5−10+2) = 0
```

任务可以 0–4 做 4 个单位、6–7 做 1 个单位，完全躲开 [4,6]；但它不能作为一个连续块躲开。**α 比抢占式 e 大，所以 INT 从第一天起就是整性推理，不是分数松弛。** v1.3 把它叫 energy，是名字借错了；这个借错掩盖了一个事实：INT 的强度已经有一部分来自"不许抢占"。

这个纠正直接决定本轮该往哪走。经典 Horn 定理说：对**抢占式**问题，用 e 的单区间条件对所有区间成立，就是抢占式可行的**充要条件**。于是：

> **负结果 0（在写代码之前就拿到）**：任何"给区间加非负权重 / 取区间并 / 做 LP 对偶"的加强，只要它加强的是**抢占式** e-规则，都不可能多闭一个实例。因为 e-规则已经完整：所有单区间通过 ⇒ 存在抢占式排程 ⇒ 任何由 e 导出的非负组合自动通过。

这替我省掉了最容易走的那条路：把 INT 写成 LP 对偶，用单纯形/对偶上升找"最好的区间权重"。不用试了，那条路的尽头是一张已经封死的墙。真正还有空间的，是**保留非抢占的 α，然后离开"每个任务只被一个区间收费一次"的世界**。

## 二、两种"装不下"

我把"装不下"拆成两种，它们对应两个不同的抽象域。

**(1) 时间装不下（MINT，多窗口整性证书）。** 一个连续块可以躲开一个瓶颈，但未必能同时躲开两个。对区间的并 `S=I_1∪I_2`（不相交），定义

```text
β_i(S) = min_{s∈[r_i, d_i−p_i]} |[s,s+p_i] ∩ S|
```

这是任务 i 在 S 里**无论如何都要做**的量。关键不等式是

```text
β_i(I_1∪I_2) ≥ α_i(I_1) + α_i(I_2)
```

因为 `min(f+g) ≥ min f + min g`（每个起点处的重叠和都不小于各自最小值之和）。等号不总成立：当任务的最优起点在躲 I_1 和躲 I_2 之间被迫二选一时，右边多出来的那部分就是**跨窗增益**。于是 `Σβ_i(S) > cap(S)` 可以在所有单区间都通过时仍然成立。两个新见证：

```text
hard3#3  n=15  S=[22,23]∪[28,31]  W=13  cap=12  +1   （v1.3 需要 555 节点）
hard3#10 n=16  S=[22,23]∪[26,27]  W= 7  cap= 6  +1   （v1.3 需要 1,349 节点）
```

**(2) 箱子装不下（PACK-SET，非抢占装箱证书）。** 取一个窗口 `[a,b]`，令 `Ω(a,b)={i : r_i≥a, d_i≤b}`——这些任务的整个执行窗都在 `[a,b]` 里，所以它们必须被**完整地**放进 m 台机器在 `[a,b]` 内的容量里，容量是 `c_k=(b−max(a,A_k))_+`。如果这些尺寸装不进 m 个容量为 `c_k` 的箱子，就无解。第三个见证：

```text
large_a#6 n=17  [39,60]  Ω=8 项 [4,9,9,10,4,6,9,9]  体积 60 ≤ 63
                 但 3 个容量 21 的箱子装不下（需 4 箱）  （v1.3 需要 1,423 节点）
```

注意这不是"体积"：体积 60 ≤ 63，INT 完全通过。这是**尺寸的整性**。它也不是 v1.3 试过的"资格子集 / 非抢占 clique"——那两个规则看的是 α 和资格，不看"整块任务的装箱"。

**(3) 序装不下（本轮没有解决）。** 剩下 3 例（hard3#2 602 节点、hard3#5 1,336 节点、large_het#1 21 节点）对 MINT 和 PACK-SET 都不触发。我试了三区间并（τ 扫到 4），0 收益。它们的 gap 大概率是**优先序 + 释放/期限的交互**，不是"量"的不够。这是本轮最重要的边界。

## 三、三个词各自落在哪

- **博弈树搜索**：DEC 的反驳树本来就是 AND/OR 树（NO = 所有子节点 NO，YES = 一个子节点 YES）。INT/MINT/PACK-SET 都是**叶子求值器**：不展开子节点就判死。MINT 的证书合成本身又是一个二人零和：证书方选 S，排程方给每个任务选起点；β 是排程方的最优反应。有效的搜索不是"所有 S"，而是"近紧区间的两两并"——这是 threat-space / quiescence 的思路：只搜对手必须应的那一手。
- **program analysis**：三个抽象域叠起来——区间域（est/d）、计数域（α/W）、多重集/装箱域（Ω 的尺寸）。MINT 是区间域与自身的**关系积**（同一个任务被两个分量同时收费）。运行顺序是标准的 narrowing：先便宜的必要条件，再在幸存者上跑贵的。v1.3 的 A-aware 缓存问题在这里有了答案：MINT 的失败域仍然对 A 单调（A 越大 cap 越小），所以它可以进 `(est,A)` 前沿；真正不能做的是把它投影成 est-only。
- **dynamic programming**：β 的计算不是状态压缩，而是"分段线性函数的最小值只在断点取到"——每个任务只要看 O(|S|) 个候选起点。PACK-SET 是一个小的装箱 DP/树，证书就是这棵树。

## 四、形式化（完整版在产物区）

固定状态 `σ=(R,A,est)` 与期限 h。对 `i∈R`：`r_i=est_i`，`d_i=h−q_i(R)`，`p_i` 为加工时间。

**定义（多窗口证书）**。设 S 是 `[0,h]` 内有限个不相交区间的并。

```text
β_i(S) = min_{s∈[r_i,d_i−p_i]} Σ_{I∈S} |[s,s+p_i]∩I|
cap(S) = Σ_k |S ∩ [A_k,∞)|
MINT:  若 Σ_i β_i(S) > cap(S)，则 FEAS(σ,h)=NO。
```

**定理 A（可靠性）**。MINT 规则可靠；INT 是 `|S|=1` 的特例；MINT 严格强于 INT（由上面两个见证）。

证明只有两步：任何可行排程把 i 放在某个连续块上，该块的起点是 β 的候选之一，所以 β_i 不超过 i 在 S 里的实际加工量；机器 k 在 S 里的可用时间不超过 `|S∩[A_k,∞)|`。求和即得。

**定义（装箱证书）**。对窗口 `[a,b]`，`Ω={i: r_i≥a, d_i≤b}`，`c_k=(b−max(a,A_k))_+`。若不存在把 `{p_i}_{i∈Ω}` 装进 m 个容量 `c_k` 的箱子（尊重资格）的分配，则 `FEAS=NO`。

**定理 B（可靠性）**。任何可行排程把 Ω 中每个任务完整地放在某台机器 k 的 `[max(a,A_k),b]` 里，因而导出上述装箱；逆否即得。

## 五、怎么找 S：一个二人零和游戏，和它的"威胁空间"

MINT 的证书合成是一个 max-min：

```text
证书方选 S；排程方给每个任务选起点 s_i；
收益 V(S) = Σ_i |[s_i,s_i+p_i]∩S| − cap(S)。
```

- **排程方的最优反应**是 β_i(S)。`g_i(s)=Σ_I |[s,s+p_i]∩I|` 是 s 的分段线性函数，断点只有 `{a_I, b_I, a_I−p_i, b_I−p_i}`，所以最小值在 O(|S|) 个点上取到。
- **证书方**的策略空间是 2^P 个子集（P 个基本时间格）。我一开始做的是 best-response 迭代：给定 S 算 β，再把"需求超过容量"的格子打开，重复。**它卡住了**：在 hard3#2/#3/#5/#10 上，从全 1 和单格出发都收敛到单区间或空集，找不到 union。坐标上升也只在 hard3#3/#10 上碰巧找到。
- 真正有效的是把证书方的策略**限制到"近紧区间的两两并"**：只保留单区间 slack ≤ 1 的候选（每个实例通常 3–10 个），枚举其中不相交的两两并（≤ 100 对）。这就是 threat-space / quiescence：不去搜索"所有可能的好棋"，只搜索"对手必须应的一手"。在 38 例上它用 32 对（hard3#3）、3 对（hard3#10）就找到了证书。

这也是本轮对"admissible ≠ useful"的第二次确认：一般 best-response 找到的一定是证书（admissible），但**不可用**；受限的两两并搜索不完整（可能漏证书），但在"只在前一层 slack ≤1 时启动"的 gate 下，它既便宜又命中。

## 六、位置经济学：这是根证书，不是节点剪枝器

v1.3 的 INT 在深处值钱（k 小、单次几十微秒）；MINT/PACK-SET 不一样：单次 0.1–0.8 ms，深处命中率却不高。深度消融：

| 配置 | 节点 | 时间 | 建表 |
|---|---:|---:|---:|
| v1.3 PACE | 5,318 | 0.339 s | 849 |
| 根 MINT（`D_m=0`） | 3,416 | 0.190 s | 551 |
| 根 MINT + 根 PACK-SET | **1,994** | **0.104 s** | **302** |
| 根 + 深度 2 MINT | 1,994 | 0.105 s | 302 |
| 根 + 深度 4 MINT + 深度 2 PACK-SET | 1,994 | 0.114 s | 302 |

深下去一个节点都不多闭，时间反而 +11%。所以本轮的结论和 v1.3 正好相反：**v1.3 是"根上一刀，深处全开"；v1.4 是"根上两刀，深处不开"**。原因是整性间隙是全局的：它由整个实例的任务窗口/尺寸决定，不随搜索状态局部化。深处的 A 让容量变窄，MINT 的 tight list 变小，但真正需要 union 的结构已经在根上的窗口里决定了。

**gating**：MINT 只在单区间 min slack ≤1 时启动；PACK-SET 只在 min slack ≤1 且窗口体积 slack ≤ max p 时启动。这不是定理，是工程 gate；它只跳过检查，不影响正确性。

## 七、结果

38 例（h=OPT−1）：

| 配置 | 节点 | 时间 | 建表 |
|---|---:|---:|---:|
| v1.2 `sub` | 433,427 | 7.28 s | 61,169 |
| v1.3 PACE | 5,318 | 0.339 s | 849 |
| **v1.4 PACE-I（根 MINT + 根 PACK-SET）** | **1,994** | **0.104 s** | **302** |

- 节点 217×（对 v1.2）、2.67×（对 v1.3）；时间 70× / 3.3×；建表 202× / 2.8×。
- 35/38 在根部闭合：10 个 DEAD；非 DEAD 的 28 例中，抢占式 e-规则闭 18 个，非抢占 α（INT）再闭 4 个（hard3#1/#6/#7/#9），MINT 再闭 2 个（hard3#3/#10），PACK-SET 再闭 1 个（large_a#6），剩 3 个（602 + 1,336 + 21 = 1,959 节点）。
- 三张新证书：hard3#3（20 个整数，检查 25 µs）、hard3#10（21 个整数，30 µs）、large_a#6（8 项 + 3 容量 + 361 节点装箱树）。它们替代了 555 + 1,349 + 1,423 = 3,327 个搜索节点。
- 正确性：3,600 组与无剪枝暴力对拍 0 不一致；`β` 与"枚举所有整数起点"的 20,000 组单元测试 0 不一致；13 条 MINT 见证逐项重算 0 无效；600 组 n=10–13 与 v1.2 `sub` 对拍 0 不一致；3 张新证书独立重放 0 无效。
- 易实例：60 个 h=OPT+5，v1.3 0.1305 s → v1.4 0.1266 s（新层开销 <1%）。

## 八、负结果

1. **加权区间 / LP 对偶**：被 Horn 定理封死。不是"没试出来"，是"不可能"。
2. **DFF（对偶可行函数）家族太弱**：`f_p(x)=⌊px/C⌋` 和"大件计数"都抓不到 large_a#6；只有精确装箱树（361 节点）抓到。所以 PACK-SET 的叶子不是"一行不等式"，而是一棵小结树。
3. **三区间并**：τ 扫到 4，0 个新闭包；MINT 的收益在"两两并"就到顶。
4. **一般 best-response / 坐标上升**：会卡在单区间；受限的两两并才是可用策略。
5. **全深度 MINT/PACK-SET**：0 个新闭包，时间 +11%。
6. **剩余 3 例**：MINT/PACK-SET 完全不触发，说明"序"这一类整性没有被覆盖。

## 九、一句话最大风险

**1,994 这个数字里，3,327 个节点的削减来自 3 个实例、每例一张叶子证书；剩下 3 个（602/1,336/21 节点）对两种整性证书完全不触发——如果真实负载的间隙是"序"而不是"量"，PACE-I 只是在根部白付 1–2 ms，然后退回 v1.3 的搜索。**
