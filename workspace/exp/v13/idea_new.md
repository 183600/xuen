# 想法区 · 第 11 轮：支配必须来自单调性

**灵感词**：多目标优化 / scalability / 渐进分析
**起点**：v1.1「X-DUB/LC*」。它把画像表的调用率压到 13%，也顺手把下一堵墙指了出来：容量层已经不是瓶颈，DEC 的组合搜索才是（PART3 中位 1.8 万、最大 6.3 万节点）。本轮不碰容量层的任何一个界，只在 DEC 的状态表示上做一次「多目标」改写。

## 一、先审计，再动手：13% 站得住，但「表的代价」量错了对象

上一轮说「表只在 13% 的临界 NO 上被调用」。我先复核了这 13% 的地基——tier 2 的 LP 对偶。把 v1.1 审计集里 208 个 `τ*>m` 的见证全部重算：207 个对偶满足「任意可行配置权重和 ≤1」且 `Σλ>m`，剩下 1 个是 `p_i>max C` 的平凡不可行。**208/208 有效**。所以间隙不是 LP 伪造的，v1.1 的层级统计可信。

但「调用率」不是「代价」。同一张表，是按 **PACK 调用次数**计费，还是按 **不同的剩余任务集 R** 计费？我在最硬的 m=3 实例上数了一下：

```text
plain:  66,550 次 NO 建表，335 个不同的 R
        每个 R 中位重建 36 次，最多 612 次；335 个 R 里 325 个至少重建 5 次
canon:  11,482 次 NO 建表，仍是 335 个 R
        每个 R 中位重建 6 次，最多 102 次
```

**同一个 R，平均被重建了 199 次（canon 后 34 次）。** 这不是「表太大」的问题，是「同一张表为不同的 A 反复重建」的问题。v1.1 的阶梯优化的是单张表的绝对代价；真正浪费的是重复。

为什么会重复？因为 DEC 到同一个 R 有很多条路径：同样的已调度集合，不同的顺序、不同的机器选择，留下不同的可用时间向量 A。**R 相同、A 不同**——这正是多目标优化里「同一个决策阶段、不同的目标向量」的标准形态。

## 二、两个「支配」，一个该杀，一个该用

v1.1 定理 7(a) 否掉了优序（majorization）支配：`A=(3,3)` 比 `A=(4,2)` 更均衡，但 `OPT(3,3)=11 > OPT(4,2)=10`。这个反例是对的，结论也对：**均衡不是可行性**。

但还有另一种支配，v1.1 没有试，因为它长得太像 7(a)：

```text
A' ≤ A（逐分量）  ⇒  若 A' 装不下，则 A 更装不下。
```

这不是「谁更均衡」，是「每台机器都不晚于对方」。它是**单调性**，不是启发式：把 A' 的每台机器都提前，任何在 A 上可行的排程在 A' 上只会更早完成、更不会超期。所以

```text
PACK(R,A',h)=NO  ∧  A'≤A   ⇒   PACK(R,A,h)=NO.
```

一句话：**优序是猜测，逐分量是定理。** 上一轮杀错了对象——该杀的是「均衡」，不是「支配」。

## 三、位置比形式更重要：这个支配放进画像表里是空操作

我本来想直接把逐分量支配塞进 `PROFILE` 的层内剪枝，省掉 v1.1 那套慢 5 倍的对偶池。写之前先算了一笔：

画像表在第 j 层处理完同样的 j 个任务，**所有可达负载向量的分量和都等于这 j 个任务的加工总时间 S_j**。于是同一层里 `A'≤A` 且 `A'≠A` 不可能——和相等，逐分量严格小就露馅了。我拿 60 个实例、414 层、1,264 个状态验证：**可比对 0 对**。

这不是实现问题，是结构问题：表内每层是单纯形的一个切片，逐分量支配在上面退化成相等。v1.1 当年在表内只能做对偶权重剪枝，不是因为它没想到支配，而是因为**支配在那里没有东西可支配**。

把同一把刀往上一格：DEC 的不同状态之间，`Σ_k A_k` 不再固定——空闲时间让不同路径的总和不同。于是逐分量支配突然有了大量可比对象。**同一个想法，在表里是 0，在 DEC 上是 10–60 倍。** 这是本轮唯一重要的定位判断。

## 四、第二个目标向量：est 不是约束，是目标

v1.1 的 memo 键是 `(R, A, est)` 的精确元组。它把 est 当成「必须记住的约束」，于是 est 不同就换一个键，哪怕一个状态的 est 逐分量更小、明显更优。

但 est 也可以被支配：

```text
est' ≤ est  ∧  A' ≤ A  ∧  同一个 R
⇒ 从 (A,est) 出发的任何可行排程，把开始时间整体提前，就是 (A',est') 的可行排程。
```

所以一个 DEC 状态真正的「目标向量」是 `(est, A)`，一共 `n+m` 维，全部越小越好；可行性对它是单调的。memo 不该是哈希，该是这个 `(n+m)` 维向量的 **Pareto 前沿**。

这个改动有多重要，我用一个消融量过：把「est' ≤ est」换成「est' = est」（同一张前沿，只允许 est 相等），最硬那个实例从 **4,647 节点涨到 194,187 节点**——比不做前沿的 canon（46,328）还差。也就是说，**本轮全部的节点收益都押在 est 的逐分量可比性上**，不是押在「前沿」这个数据结构上。

## 五、算法轮廓：PO-LC

在 v1.1 的阶梯上只加三样东西，不动任何一层界：

1. **tier 1.5 `FRONT`**：按 `(R,h)` 缓存已证明 `PACK=NO` 的 A 的 Pareto 极小元。查询 `∃A'≤A`，命中就直接返回 NO，跳过 tier 2/3。它之所以合法，是因为 LC-PACK 在进容量层之前已经做过 DEAD 检查，所有到达这里的任务都满足 `est_i ≤ T_i`；此时 `E_i={k:A_k≤T_i}` 与 est 的具体数值无关（引理 1）。
2. **DEC 级 `(est,A)` 前沿**：按 `(R,h)` 缓存整棵子树失败的 `(est,A)`，查询要求逐分量 ≤。这是节点数下降的真正来源。
3. **孪生机器商**：若两台机器对 R 中所有任务的资格列相同，则交换它们不改变子问题；把 A 在孪生类内排序作为规范形。统一资格时这是 `m!` 的精确商。

再加两个工程约束：前沿上限 K（查询 `O(mK)`，超限按「覆盖盒体积」淘汰，只丢剪枝不丢正确性）；证书语言加一个 `FRONT` 节点（向量不等式 + 指向一个基础证书的指针），检查器按 DAG 重放。

## 六、渐进分析：三句话

1. **前沿多大**：`[0,h]^m` 的逐分量反链宽度是 `O(h^{m−1})`（m=2 时就是一条 ≤h+1 的阶梯）。实测 m=3 的 12 个硬实例上 |F| 最大 12——比上界小三个数量级，但上界是真的。
2. **何时回本**：查询 `c_q=O(mK)`，建表 `c_t=Θ(nH^{m−1})`。命中率 ρ 的盈亏平衡是 `ρ* = c_q/(c_t+c_q)`。实测 n=40–120、m=3、H=100 时 `ρ* = 0.005%–0.008%`——**几乎任何非零命中率都回本**。渐近上 `ρ* = Θ(mK/(nH^{m−1})) → 0`。
3. **什么被限住、什么没有被限住**：每个 R 的前沿**内存** ≤ `O(h^{m−1})`（或 cap K），查询 `O(mK)`；但**建表次数不被前沿大小界住**——一个严格递减的 A 序列 `(10,10),(9,9),(8,8),…` 每次都新、每次建表，前沿始终只有 1 个元素。前沿限住的是内存与查询代价，不是最坏建表次数；实测建表率 0.32，这是经验值。诚实地说：scalability 的渐近保证在内存与单次判定，不在最坏建表数。

孪生商是精确的 `1/|Aut|`，实测 m=3 统一资格下节点比 `0.174`（`1/6=0.167`），m=2 是 `0.538`（`1/2=0.5`），异构资格下精确为 `1.000`（没有孪生）。三个数字把「这是对称性，不是别的」钉死了。

## 七、实验设计与结果（细节在产物区）

- 12 个 m=3 硬实例（n=12–16，h=OPT−1）：plain 1,055,757 节点 / 12.40 s；PO 69,690 / 1.18 s；完整 PO-LC 1.22 s（阶梯再省 81% 建表）。**节点 15.2×，时间 10.5×**；单实例最好 58× 节点、33× 时间；最差 6.9×（#3），最大实例 #4 仍有 10.5×。
- 47 个 m=2 硬实例：plain 14,773 → PO 4,989 节点（3.0×），建表 5,643 → 1,682（完整 PO-LC 2,362）。
- 6 个异构资格 m=3：canon 恰好 1.000×，sub 前沿仍有 1.48×——两个机制互补，不重叠。
- 120 个容易实例：PO 比 plain 慢 7.0%（前沿不命中时的纯开销）。
- K 消融：K=8 保住 96% 的节点收益，K=1 仍有 1.35×。前沿大小实测 ≤12，K 在常规实例上根本不 binding。

## 八、负结果（本轮同样重要）

1. **tier 0 的阶梯在 DEC 节点上省表不省时**：ladder_front 把建表从 38,837 压到 4,911（−87%），但时间 2.73 s vs canon 2.72 s——每次贪心的 O(n log n) 与它省下的那张小表等价。阶梯的价值随 n、H 增长才会显出来；在 DEC 子问题（n≤16）上它是中性的。
2. **pack 前沿不减节点**：它只把「建表」换成「查表」，节点数一根不差（1.000×）。真正减节点的是 `(est,A)` 前沿。这一点必须写清楚，否则会把两个机制的功劳混在一起。
3. **`(est,A)` 前沿没有好的最坏界**：它是 n+m 维的，反链上界是指数级的；K 是唯一的护栏。收益最大的机制恰好是理论保证最弱的机制。
4. **异构资格下孪生商归零**：6 个异构实例上 canon 节点比精确 1.000。对称性不是免费的，它要求资格对称。

## 九、一句话最大风险

**本轮全部的节点收益都押在 `(est,A)` 的逐分量可比性上：`est` 相等消融让 15× 直接塌成 0.5×（比 canon 还慢），而真实 DEC 的 est 分布由前驱结构和资格共同诱导，本轮只在随机 DAG 上验证过，没有对抗性实例能保证它不会塌。**
