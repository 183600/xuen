# 产物区 · v1.2：X-DUB/PO*

> PO = Pareto-Optimal：把 DEC 的状态从「精确哈希键」改成「(est,A) 的 Pareto 前沿」，把容量层的 A 从「重复建表」改成「前沿查询」。
> 中文名：单调支配与状态前沿
> 状态：设计稿 + 一整套可运行实现与对拍；400 例跨模式一致性、750 例无剪枝暴力对拍、400 条赋值见证独立复核、208 条 tier-2 对偶复核；12 个 m=3 硬实例、47 个 m=2 硬实例、6 个异构资格实例、120 个易实例开销、1 组建表微观基准、K 消融与 est-相等消融。未接 PSPLIB，未做形式化验证，未在 n≥18 的对抗实例上验证前沿退化。

## 0. 版本关系与本轮增量

v1.1 的资产全部保留：`LC-PACK` 的 0/0.5/1/2/3 层、`LC-DEC`、`CHECK-LC`、`PROFILE` 的位并行与对偶池。

v1.2 只改 **DEC 的状态表示**，不动任何一层界：

1. **tier 1.5 `FRONT`**（容量层）：按 `(R,h)` 维护已证 `PACK=NO` 的 A 的 Pareto 极小元；查询 `∃A'≤A`，命中即返回 NO，跳过 tier 2/3。合法性来自引理 1（非 DEAD 态下 E_i 与 est 的具体值无关）与定理 2（PACK 对 A 单调）。
2. **DEC 级 `(est,A)` 前沿**：按 `(R,h)` 维护整棵子树失败的 `(est,A)`；查询要求 `est'≤est ∧ A'≤A*`。合法性来自定理 5（整体提前的排程仍可行）。
3. **孪生机器商 `CANON`**：资格列相同的机器可互换；A 在孪生类内排序作规范形。合法性来自定理 6。
4. **`FRONT` / `FRONT-SUB` 证书节点**：向量不等式 + 指向一个基础证书的指针，检查器按 DAG 重放。合法性来自定理 3/5。

退化关系（三个开关全关）：

```text
关 FRONT、FRONT-SUB、CANON，并把 PACK 只留 tier 3  → 逐字回到 v1.1 的 PC-DEC 骨架（精确 memo + 画像表）
关 FRONT、FRONT-SUB，只留 CANON → 本轮的 plain→canon 对照
关 FRONT-SUB（保留 FRONT+CANON）→ 本轮的 "front" 对照，节点数与 canon 完全相同
```

## 1. 符号

| 符号 | 含义 |
|---|---|
| `I=(n,m,p,E,≺,h)` | 实例：加工时间、资格、优先图、截止期 `h` |
| `σ=(R,A,est)` | DEC 状态：未调度集、机器可用时刻、最早开始 |
| `q_i(R)` | `i` 到 `R` 内汇点的最长路（不含 `p_i`） |
| `T_i=h−p_i−q_i(R)` | `i` 的最晚可开工上界（超过即死） |
| `E_i(σ,h)` | `{k∈E_i : max(A_k,est_i)≤T_i}` |
| `DEAD(σ)` | `∃i∈R: est_i>T_i` 或 `E_i(σ,h)=∅` |
| `K(R,A,h)` | 由 `(R,A,h)` 唯一决定的容量实例：容量 `h−A_k`，资格 `{k∈E_i:A_k≤T_i}` |
| `PACK(σ,h)` | `K(R,A,h)` 的可行性（`DEAD` 时约定为 NO） |
| `N_{R,h}` | `{A : K(R,A,h) 不可行}`，**NO 上集** |
| `F_{R,h}=Min(N_{R,h})` | 容量层 Pareto 前沿 |
| `G_{R,h}` | DEC 层已证子树失败的 `(est,A)` 集合 |
| `A*` | `CANON_R(A)`，孪生类内降序排序 |
| `c_t, c_q, ρ` | 单次建表代价、单次前沿查询代价、命中率 |

## 2. 形式定义

**定义 1（状态与可行性）**。`FEAS(σ,h)` 为真当且仅当存在赋值 `α:R→[m]` 与开始时间 `t_i`，满足

```text
α(i)∈E_i,   t_i ≥ max(A_{α(i)}, est_i),   t_i+p_i+q_i(R) ≤ h,
i≺j ⇒ t_j ≥ t_i+p_i,   同机任务不重叠。
```

**定义 2（容量层）**。`PACK(σ,h)` 为真当且仅当存在 `α:R→[m]` 使 `α(i)∈E_i(σ,h)` 且 `∀k: Σ_{α(i)=k}p_i ≤ h−A_k`。

**定义 3（NO 上集与前沿）**。固定 `(R,h)`，称 `K(R,A,h)` 不可行若定义 2 的赋值不存在。令

```text
N_{R,h} = { A∈[0,h]^m : K(R,A,h) 不可行 },
F_{R,h} = Min(N_{R,h})   （逐分量偏序下的极小元）.
```

**定义 4（tier 1.5 `FRONT`）**。若 `DEAD(σ)=false` 且 `∃A'∈F_{R,h}: A'≤A*`，返回 `(NO,1.5,(A*,A',base))`；`base` 是 `A'` 的 tier 1/2/3 证书。

**定义 5（DEC 前沿 `G`）**。`G_{R,h}` 是若干 `(est',A')` 的集合，每个元素带一个「整棵子树 NO」的证书。若 `∃(est',A')∈G: est'≤est ∧ A'≤A*`，返回 `NO(FRONT-SUB)`。

**定义 6（孪生商）**。`k ~_R l` 当且仅当 `∀i∈R: k∈E_i ⟺ l∈E_i`。`CANON_R(A)` 在每个 `~_R` 等价类内把 A 的分量降序重排。

**定义 7（PO-LC-PACK）**。

```text
PO-LC-PACK(σ,h):
  1  q ← TAILS(R)                                  # O(n+|E|)
  2  if ∃i: est_i+p_i+q_i>h: return (NO,0.5,DEAD(i))
  3  if ∃i: E_i(σ,h)=∅:      return (NO,0.5,DEAD(i))
  4  α ← GREEDY(σ,h)                               # 强制 + BFD；O(n log n)
  5  if α≠⊥: return (YES,0,α)
  6  t ← DFF(σ,h)                                  # O(n·p_max)
  7  if t≠⊥: return (NO,1,t)
  8  A* ← CANON_R(A)
  9  if ∃A'∈F_{R,h}: A'≤A*: return (NO,1.5,FRONT(A*,A',base(R,h,A')))
 10  λ ← LP(σ,h)                                   # 可选层；poly(n)
 11  if λ≠⊥: return (NO,2,λ)
 12  ok ← TABLE(σ,h)                               # O(n·|L|max)
 13  if ¬ok: F_INSERT(R,h,A*)                      # 维护反链，上限 K
 14  return (ok,3,TABLE-WIT)
```

**定义 8（PO-DEC）**。

```text
PO-DEC(σ,h):
  1  if R=∅: return YES([])
  2  if DEAD(σ): return NO
  3  if exact-memo[(R,A,est)]: return NO
  4  A* ← CANON_R(A)
  5  if ∃(est',A')∈G_{R,h}: est'≤est ∧ A'≤A*:
  6      return NO(FRONT-SUB)
  7  (ans,tier,wit) ← PO-LC-PACK(σ,h)
  8  if ans=NO: exact-memo[(R,A,est)]←h; return NO(tier,wit)
  9  for i in READY(R) sorted by slack:
 10      for k in E_i(σ,h):
 11          t ← max(A_k,est_i);  A' ← A with A'_k=t+p_i
 12          est' ← PROPAGATE(est,i,t+p_i)
 13          r ← PO-DEC(R\{i},A',est',h)
 14          if r=YES: return YES([(i,k,t)]+r)
 15  G_INSERT(R,h,(est,A*)); exact-memo[(R,A,est)]←h
 16  return NO(RESOLVE)
```

**定义 9（证书语言）**。

```text
CERT ::= YES-ASSIGN(α)                        # tier 0
       | NO-DEAD(i)                            # tier 0.5
       | NO-DFF(t)                             # tier 1
       | NO-FRONT(A,A',CERT')                  # tier 1.5，A'≤A
       | NO-LP(λ)                              # tier 2
       | NO-TABLE(layers)                      # tier 3
       | NO-FRONT-SUB(est,est',A,A',CERT')     # DEC 前沿，est'≤est ∧ A'≤A
       | NO-RESOLVE(children)                  # 子节点全 NO
       | YES-DEC(i,k,t,CERT)                   # 选一个子节点 YES
```

检查器按标签选规则：`NO-FRONT` 只需 `O(m)` 验证 `A'≤A`，再把 `CERT'` 对 `(R,A',h)` 重放；`NO-LP` 验证 `λ≥0, Σλ>m` 且每台机器的背包最大值 ≤1；`NO-TABLE` 重放逐层表到空。

## 3. 定理与证明

### 定理 1（非 DEAD 态下 est 只进入阈值）

若 `DEAD(σ)=false`，则 `E_i(σ,h)={k∈E_i : A_k≤T_i}`，与 `est` 的具体数值无关。

**证明**：`DEAD=false` 给出 `est_i≤T_i`，且至少一个 `k` 满足 `A_k≤T_i`。于是
`max(A_k,est_i)≤T_i ⟺ A_k≤T_i`（`est_i≤T_i` 时二者等价）。故 `E_i` 只由 `A` 与 `T_i` 决定。∎

**作用**：容量层的前沿可以只按 `(R,h)` 建，不必把 est 塞进键。这是 tier 1.5 存在的先决条件。

### 定理 2（PACK 对 A 单调）

同 `(R,h)`，若 `A'≤A` 且 `DEAD` 均为假，则 `K(R,A',h)` 可行 ⟸ `K(R,A,h)` 可行；等价地
`K(R,A',h)` 不可行 ⇒ `K(R,A,h)` 不可行。

**证明**：`A'≤A` 给出容量 `h−A'_k ≥ h−A_k` 与资格 `{k:A'_k≤T_i}⊇{k:A_k≤T_i}`。任何对 `(R,A)` 可行的赋值对 `(R,A')` 仍可行。取逆否。∎

### 定理 3（tier 1.5 可靠）

若 `DEAD(σ)=false` 且 `∃A'∈F_{R,h}: A'≤A*`，则 `PACK(σ,h)=NO`。

**证明**：`A'∈F⊆N` 给出 `K(R,A')` 不可行；定理 2 给出 `K(R,A*)` 不可行；定理 1 给出 `PACK(σ,h)=PACK(R,A*,h)=NO`。∎

### 定理 4（前沿是唯一极小精确缓存）

`N_{R,h} = ↑F_{R,h}`。并且若 `S⊆N` 满足 `↑S=N`，则 `F⊆S`。

**证明**：`[0,h]^m` 有限，偏序良基，故 `N` 的每个元素都 ≥ 某个极小元；反包含显然。若 `a∈F` 而 `a∉S`，由 `a∈↑S` 存在 `s∈S, s≤a`；`s∈N` 与 `a` 极小推出 `s=a`，矛盾。∎

**解释**：任何「精确回答 A 是否在 NO 区域」的缓存都必须包含 `F`。前沿不是一种实现选择，而是这个区域的**极小生成元**。任何比它更小的缓存都只能是不精确的（但仍然可以 sound：漏剪枝，不误判）。

### 定理 5（DEC 前沿可靠：整体提前）

设 `σ=(R,A,est)`，`σ'=(R,A',est')`，`A'≤A`，`est'≤est`。若 `FEAS(σ',h)=NO`，则 `FEAS(σ,h)=NO`。

**证明**：反设 `σ` 有可行解 `(α,t)`。对每个 `i`，
`t_i ≥ max(A_{α(i)},est_i) ≥ max(A'_{α(i)},est'_i)`；优先约束与截止约束只涉及 `t,p,q`，均不变。故同一 `(α,t)` 对 `σ'` 可行，矛盾。∎

### 定理 6（孪生机器商）

设 `π` 是机器排列且 `∀i∈R: k∈E_i ⟺ π(k)∈E_i`。则 `K(R,πA,h)` 与 `K(R,A,h)` 同可行；`FEAS` 同。故 `CANON_R(A)` 可替代 `A` 进入键与支配测试（支配按群作用解释）。

**证明**：`π` 作用在赋值上，资格保持、容量置换；排程随之置换。∎

**推论**：若 `∃A'∈F_{R,h}: A'≤CANON_R(A)`，则 `A` 也在 `N` 中。因为 `CANON_R(A)=π(A)` 对某个 `π∈Aut_R`，而 `N` 对 `Aut_R` 不变。

### 定理 7（表内支配是空操作）

画像表第 `j` 层在放完同一组任务 `S_j` 后，任何可达负载向量 `ℓ` 满足 `Σ_k ℓ_k = p(S_j)`。故 `ℓ'≤ℓ` 推出 `ℓ'=ℓ`。

**证明**：负载是被放任务的加工时间之和，层内已放集合相同。∎

**含义**：多目标支配必须放在 DEC 层（跨路径时 `ΣA` 不固定，因为空闲时间不同），放在表内没有对象可支配。这解释了 v1.1 表内只能用对偶权重剪枝，也解释了优序支配（majorization）失败后为什么不该放弃「支配」本身。

### 定理 8（盈亏平衡命中率）

设单次建表代价 `c_t`、单次前沿查询 `c_q=Θ(mK)`、命中率 `ρ`。每次容量调用的期望代价为 `(1−ρ)c_t+ρc_q`，前沿有利当且仅当

```text
ρ > ρ* = c_q/(c_t+c_q).
```

v1.1 的 `c_t=Θ(n·H^{m−1})`（或位并行 `Θ(n·B^m/64)`），故 `ρ*=Θ(mK/(nH^{m−1}))→0`。

### 定理 9（前沿大小，不是建表次数）

`|F_{R,h}| ≤ W(h,m)`，其中 `W` 是 `[0,h]^m` 的逐分量反链宽度；`W=O(h^{m−1})`（乘积链的 Sperner 性），`m=2` 时 `W≤h+1`。加 cap 后 `|F|≤K`。

**注意（必须说清）**：建表次数**不**被 `W` 界住。一个严格递减的 A 序列 `(10,10),(9,9),(8,8),…` 每个都是新到达且非被支配，每次都建表，而前沿始终只有 1 个元素。前沿限住的是**内存与查询代价**，不是最坏建表次数。实测建表率（PO 的建表数 / canon 的建表数）为 0.32，这是经验值，不是定理。

### 定理 10（无害）

固定 `m,K`，PO 的每节点额外代价为 `O(mK)=O(1)`，且它不会增加建表次数。故

```text
T_PO ≤ T_v1.1 + O(N)     （最坏情形只多一个常数）
T_PO = O(N·(n+mK) + B·c_t)  vs  T_v1.1 = O(N·c_t)
```

`B≤N`，所以渐近类不变；当 `B<N` 时严格更优。本轮实测 `B/N=0.32`（m=3）。

## 4. 复杂度

| 对象 | 时间 | 空间 |
|---|---|---|
| `CANON_R` | `O(n·m)`，按 R 缓存 | `O(m)` |
| tier 0 | `O(n log n)` | `O(n)` |
| tier 1 | `O(n·p_max)` | `O(1)` |
| tier 1.5 查询 | `O(m·|F|) ≤ O(mK)` | `O(K)` |
| tier 1.5 插入 | `O(m·|F|)+O(K log K)`（淘汰） | `O(K)` |
| tier 3 | `O(n·m·|L|max)`，`|L|max=O((mH)^{m−1})` | `O(|L|max)` |
| DEC 前沿查询 | `O((n+m)·|G|)` | `O(K)` |
| 证书检查（FRONT 链） | `O(链长·m + 基础证书)` | `O(链长)` |

整体：

```text
T_PO = O( N·(n + mK) + B·c_t ),   B = 实际建表次数
S_PO = O( Σ_R min(|F_R|,K) + N·m )   （精确 memo 仍是主内存项）
```

### 5.4 消融（同一 12 例，节点总和 / 时间总和 / 建表）

| 配置 | 节点 | 时间 | 建表 |
|---|---:|---:|---:|
| plain（v1.1 精确 memo） | 1,055,757 | 12.40 | 224,960 |
| + CANON | 181,908 | 2.72 | 38,837 |
| + CANON + FRONT（容量前沿） | 181,908 | 2.65 | 32,494 |
| + CANON + FRONT + G（**PO**） | 69,690 | 1.18 | 12,464 |
| + CANON + FRONT + ladder（v1.1 阶梯全开） | 181,908 | 2.73 | 4,911 |
| **PO + ladder（完整 PO-LC）** | **69,690** | **1.22** | **2,362** |

三句话：

1. **CANON 与 G 是可加的，FRONT 只省表不省节点**：`FRONT` 的节点比精确 1.000，建表 −16.3%；`G` 把节点从 181,908 打到 69,690，建表打到 12,464。
2. **阶梯在 DEC 子问题上省表不省时**：建表 −87%（38,837→4,911），时间 2.73 vs 2.72。每次 BFD 的 `O(n log n)` 与它省下的小表等价。完整 PO-LC 再加阶梯，时间 +3%，建表再 −81%。
3. **v1.1 的瓶颈不是表，是路径数**：plain 的 22.5 万次建表对应 335 个 R（平均 199 次/R），阶梯优化的是单表常数，G 优化的是「同一个 R 不再重复判定」。

| 2 | 108,244 | 66% |
| 8 | 73,827 | **96%** |
| 48 | 69,690 | 100% |

K=1 仍有 1.35× 节点收益；K=8 已收回 96%。前沿大小实测 ≤12，所以 K 在常规实例上不是调参点，只是内存护栏。

### 5.6 异构资格（6 个 m=3 硬实例，`elig_p=0.65`）

| 指标 | plain | canon | PO |
|---|---:|---:|---:|
| 节点总和 | 20,074 | 20,074 | **13,564** |
| 相对 plain | 1.000 | **1.000** | **0.676** |

**canon 精确归零**（没有孪生机器），而 `(est,A)` 前沿仍有 1.48×。两个机制互不重叠：一个吃资格对称，一个吃状态可比性。

### 5.7 易实例开销（120 例，`h=LB+8`）

`plain 0.0679 s` vs `PO 0.0727 s`：**+7.0%**。前沿不命中时只付 `O(mK)` 查询与一次排序；这是定理 10 的常数项。

### 5.8 建表微观基准（m=3，H=100）

| 剩余任务 n | 建表 | 前沿查询（K≤8） | ρ* |
|---:|---:|---:|---:|
| 20 | 4.7 ms | 1.19 µs | 0.025% |
| 40 | 14.0 ms | 1.18 µs | 0.0085% |
| 80 | 25.4 ms | 1.15 µs | 0.0052% |
| 120 | 19.4 ms | 1.16 µs | 0.0059% |

`ρ*` 是盈亏平衡命中率：在 n≥40 时**千分之一以下的命中率就回本**。实测命中率 16.3%（FRONT 单独）到 68%（G 参与后），远在平衡点之上。

### 5.9 负结果

1. **`est` 相等消融**：把 `G` 的 `est'≤est` 换成 `est'=est`，12 例节点从 69,690 涨到 **850,367**（比 canon 的 181,908 还差 4.7×）；最硬实例 #10 从 4,647 涨到 **194,187**。**本轮全部节点收益都来自 est 的逐分量可比性，不来自「前沿」这个容器。**
2. **表内支配空操作**（定理 7）：1,264 个状态 0 对可比。这也解释了 v1.1 的对偶池为什么是表内唯一 sound 的选择。
3. **阶梯省表不省时**（5.4）：在 n≤16 的 DEC 子问题上，BFD 的常数 ≈ 小表的常数。
4. **异构资格下孪生商归零**（5.6）：对称性不是免费的。
5. **没有最坏建表界**（定理 9 的注意）：递减 A 序列可以每次都是新前沿点。前沿限住内存与查询，不限最坏建表次数。

### 5.10 未做

- PSPLIB / 真实 RCPSP：未接。
- n≥18 的对抗实例：只跑了 6 个 n=18–22 的随机实例，其中 5 个在 `h=OPT−1` 被能量/截止界平凡闭合，唯一非平凡的是 n=18、plain 187,270 → PO 22,557（8.3×）。没有对抗性构造。
- 多核：未做（沙箱限制同 v1.1）。
- 形式化验证：无；正确性是纸面证明 + 1,150 组随机对拍、2,000 次模式判定、1,510 条见证复核。

## 7. 已知风险

1. **`est` 可比性是承重墙**：`est'=est` 消融让 15× 塌成 0.5×。随机 DAG 上 est 经常可比（因为同层状态的 est 由同一组前驱诱导），但资格碎片化、多前驱、长尾链可能让它不可比。**这是本轮最大的未验证假设。**
2. **`G` 没有好的最坏界**：`(n+m)` 维反链，K 是唯一护栏；K 太小会退化（K=1 只剩 42% 收益），K 太大会让查询变慢。
3. **容量前沿的合法性依赖 `DEAD` 先于 `PACK`**：定理 1 要求 `est_i≤T_i`。任何把 `PACK` 提到 `DEAD` 之前的重构都会让 tier 1.5 变得不可靠。实现里应加断言。
4. **canon 只在资格对称时有效**：异构实例上精确 1.000；如果真实 RCPSP 的资格高度碎片化，`m!` 的收益全部消失。
5. **建表次数没有最坏界**（定理 9）：最坏情形下 PO 与 v1.1 同阶，只多常数；「15×」是 12 个随机硬实例的中位数附近，不是分布保证。
6. **选例偏差**：12 个实例是按「plain 节点 > 3000」筛出来的，15.2× 不是无偏估计，而是「在需要它的区间里」的估计。
7. **时间常数是 Python 的**：`ρ*=0.005%` 依赖 Python 大整数建表 vs Python 循环查询；换 C 后两边都变，比值可能变一个数量级（但方向不变）。
8. **证书链可能长**：`FRONT` 链最坏长度 = 前沿大小；检查器要重放每个基础证书。没有实现路径压缩。
9. **LP 层的 sound 性只抽样复核**：208/208 是审计集上的，不是证明。
10. **没有形式化验证**：定理 1–10 是纸面证明 + 随机对拍。

---

## 8. 一句话最大风险

**本轮全部的节点收益都押在 `(est,A)` 的逐分量可比性上：est 相等消融让 15× 直接塌成 0.5×（比 canon 还慢），而真实 DEC 的 est 分布由前驱结构和资格共同诱导，本轮只在随机 DAG 上验证过，没有对抗性实例能保证它不会塌。**
