# 想法区 · 第 11 轮：把「基准」审到不能骗人

**灵感词**：基准测试 / 算法设计 / computational method  
**起点**：v1.1「X-DUB/LC*」。它留下了一个很诱人的数字：临界异构资格实例中，DFF 闭合 64%、LP 闭合 87%，只剩 13% 需要画像表；还有一个 7 项手算例子，宣称「无强制项、DFF=H、LP 可行、表 5 个状态」。

本轮从一句不客气的自问开始：

> **这 13% 里，有多少是「表真的必要」，有多少只是「我们用的 LP 太弱」？**

## 一、先拆掉唯一的「表见证」

把 7 项例子重抄一遍：`m=3, H=8, p=(1,1,4,8,3,1,4)`，资格

```text
E_0={0,1}  E_1={1,2}  E_2={1}  E_3={1,2}
E_4={1,2}  E_5={0,1}  E_6={1,2}
```

先算一个 v1.1 没算的集合：`M={1,2}`。哪些任务只能在这两台机器上？

`E_1,E_2,E_3,E_4,E_6 ⊆ {1,2}`，p 之和 `1+4+8+3+4 = 20`；两台机器容量 `8+8=16`。**20 > 16**。

这是一个 `O(2^m·n)` 的子集体积割：只要一个任务集合的资格全落在 M 内，它们的总加工就不能超过 M 的总容量。它甚至在 DFF 之前就能判 NO。所以：

- DFF=8=H，确实不闭合；
- 旧 LP `τ*=2.833≤3`，确实「LP 可行」；
- 画像表确实 5 个状态就空了；
- **但它不是「只有表能判」——一个子集体积割就够了。**

这不是一个孤例。v1.1 的 `DFF` 只检查 `M=全部机器`；`FORCE` 只检查 `|E_i|=1` 的任务。两者之间有一整族 `M`，v1.1 一个都没检查。7 项例子恰好落在 `M={1,2}` 上。

## 二、旧 LP 不是「错」，是「机器盲」

我一开始以为旧 LP 的 `τ*=2.833` 是代码 bug。查了 `exp/v09/lp.py` 才明白：它的列是「能装进某一台机器的任务子集」，约束只有

```text
Σ_{S∋i} y_S = 1     （每个任务覆盖一次）
Σ_S y_S ≤ m         （总列数不超过 m）
```

它没有「同一台机器上的模式数 ≤1」这条约束。对统一容量、无资格，这不是问题：机器可互换，总列数 ≤m 就是全部。但对异构资格，它会把「只能上机 1 的 4」和「只能上机 1 的另一个 4」放进两个不同列，然后说总共 2 列 ≤3。它没有看见这两列其实抢同一台机器 1。

**必须说清楚：这不是 unsound。** 旧 LP 仍然是整数问题的松弛，`τ*>m` 仍然是合法的 NO 证书；它的对偶 `λ` 仍然满足它自己的全部列约束。问题是它**太弱**，弱到把「其实一个子集割就能判」的实例标成「LP 可行」。v1.1 把这个弱松弛当成了阶梯的最后一层，于是 13% 的「间隙」里混进了大量「LP 没看见的东西」。

正确的对象是**逐机器配置 LP**（per-machine configuration LP）：

```text
y_{k,S} ≥ 0,  S⊆E_k,  p(S)≤C_k
Σ_{k,S∋i} y_{k,S} = 1          ∀i
Σ_S y_{k,S} ≤ 1                ∀k
min Σ y
```

它给每台机器一个独立的模式预算。7 项例子在这个 LP 下不可行；旧 LP 可行。两者的差，就是 v1.1 的「13%」。

## 三、重跑 101 个临界实例：13 → 0

我用 v1.1 的 `Random(5)` 重新生成同一批 101 个异构资格临界实例（`H=L_PACK−1`），逐个算：

| 层 | 纯分箱 120 | 异构资格 101 |
|---|---:|---:|
| DFF | 115 | 65 |
| SUBCUT（所有 M 的体积/子集 DFF） | 115 | 74 |
| 赋值 LP（ALP） | 114 | 71 |
| 旧机器盲 LP | **120** | **88** |
| per-machine CLP | **120** | **101** |
| 只剩画像表 | 0 | **0** |

那 13 个「旧 LP 可行」的实例，逐项重算：

- 5 个被 SUBCUT 直接关闭；
- 5 个被 ALP 关闭（它们其实有更简单的逐机器容量矛盾）；
- **13 个全部被 per-machine CLP 关闭**；
- 其中 8 个是真正的 ALP 间隙（SUBCUT、ALP 都不闭合），但 CLP 仍然闭合。

所以 v1.1 的「13% 只剩表」在这批样本上应改成 **0/101**；加上 120 个纯分箱，是 **0/221**。这不是说表永远不需要，而是说：**v1.1 用来给表定价的那批实例，一个都不需要表。**

## 四、computational method：列生成把正确的 LP 变成可跑的

per-machine CLP 的列是指数多的。直接枚举只适合 `n≤13`；要在 `n≥50` 用，需要列生成。

主问题带 deficit `a_i` 和 surplus `s_i`：

```text
min Σ a_i
s.t. Σ_{k,S∋i} y_{k,S} + a_i − s_i = 1
     Σ_S y_{k,S} + t_k = 1
     y,a,s,t ≥ 0
```

对偶是 `max Σλ_i − Σμ_k`，约束 `Σ_{i∈S}λ_i ≤ μ_k`。定价就是每台机器一个 0/1 背包：`max Σλ_i`，容量 `C_k`。若某台机器的背包值 `> μ_k`，对应模式负 reduced cost，加入主问题；若所有机器都不定价，当前 `(λ,μ)` 对整个 LP 可行。此时若 `Σa>0`，它就是 Farkas 证书；若 `Σa=0`，LP 可行。

在 101 个异构实例上：0 个可行，最大 45 列、18 轮、2.5 秒；13 个间隙实例 0.1 秒。这个量级说明：**正确的 LP 不是「理论上更强但跑不动」，它在基准规模上是可跑的。**

## 五、一个反直觉的表代价实验

我原以为「植入一个小核 + 很多填充项」会让画像表爆炸。结果相反。

表按 `p` 降序处理任务。核里的任务通常是大任务，所以表**先处理核**，在核上就死了，根本走不到填充项：

- `m=3,H=1000`，4 项体积核 `(800,500,500,300)`，加 246 个 size-1 填充项，`n=250`：全表 **5 个状态 / 0.001 秒**；SUBCUT 在 `M={1,2}` 上 `2100>2000` 关闭；删除过滤器 250 次调用、0.687 秒，把证书压回 4 项。
- `m=3,H=690`，7 项 CLP 核（v1.1 的 row 68，scaled ×30），加 250 个填充项，`n=257`：DFF=674、SUBCUT=674，都 `<690` 不闭合；全表 **7 个状态**；CLP 在 7 项核上 0.037 秒判不可行（13 列、9 轮）。

这让我重新归类「表的代价」：

1. **YES 实例**：表可能很大（v1.1 的 47.5 秒墙就是），但 greedy 0.04 ms 就给赋值，阶梯根本不该建表。
2. **有小核的 NO 实例**：表按 p 降序先撞核，状态数由核决定，不由 n 决定。
3. **没有小核的全局 NO 实例**：这才是表真正可能大的地方；它也正是 per-machine CLP 可能可行、整数不可行的「真间隙」。

第 3 类我找了：358 个随机 NO（m=2/3，n≤9）、108 个 3-partition 型 NO（n=9,H=50,p∈[13,24]），加上 221 个临界实例——**一个真间隙都没找到**。所以表在本轮所有基准上的触发集是空的。

## 六、LC2-PACK：把「表的调用条件」写死

```text
tier 0   GREEDY   : BFD + 扰动，YES 见证 = 赋值          O(n log n)
tier 0.5 FORCE    : |E_i|=1 的任务扣容量                 O(n)
tier 1   DFF      : t·⌈B_t/m⌉ > Cmax ⇒ NO，见证 = t      O(n·p_max)
tier 1.5 SUBCUT   : 所有 M⊆[m] 的体积/子集 DFF ⇒ NO      O(2^m·n·p_max)
tier 2   CLP      : per-machine 配置 LP（列生成）⇒ NO    poly 列数经验值
tier 2.5 CORE     : 单调核提取，压缩 NO 证书             O(n) 次 oracle
tier 3   TABLE    : 只在 CLP 可行时，建在核上            O(k·H^{m−1})
```

关键不变式：**只有 0/0.5/1/1.5/2 全不闭合，才允许 CORE/TABLE。** 表从「默认路径」变成「真间隙专用路径」，而且只建在核上。

CORE 的依据是单调性：若 `R'⊆R` 且 `PACK(R')=NO`，则 `PACK(R)=NO`。删除过滤器从 R 出发，若 `S\{i}` 已被前几层判 NO，就删 i；每一步都保留一个 NO 证书。最后若 S=R 且没有删除发生，才在 R 上建表；若发生过删除，S 已经是 NO，表只用来复算证书。

## 七、本轮真正的方法论产出：基准有效性四条

这轮最重要的不是新层，而是给「表基准」定了四条有效性条件：

- **V1** `PACK=NO` 有独立见证（不能只靠待测的表）；
- **V2** 阶梯中所有 sound 层都可行（否则表不该被调用）；
- **V3** 证书可独立检查（每层有自己的规则）；
- **V4** 没有更小的已闭合核（否则表的大小不代表问题难度）。

v1.1 的 7 项例子违反 V2；101 个临界样本里的 13 个违反 V4（per-machine CLP 全关）。所以那 13% 不是「问题的间隙率」，是「弱 LP 的间隙率」。**基准测试的第一个 bug，往往在松弛里，而不在算法里。**

## 八、一句话最大风险

**per-machine CLP 把建表率压到 0/221，但列生成是新的单点；如果它在真实 DEC 节点上不收敛，我们回退的画像表没有任何 n≥250 的真间隙基准可依。**
