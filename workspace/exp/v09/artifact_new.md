## 0. 版本关系与本轮增量

v0.8 的资产全部保留：

- `(R,A,est)` 状态、Q-DOM、focal + guide、路径最大下界 `F`、证明 DAG 的局部检查规则；
- 逐节点能量界 `E(R,A)`、截止期界、阈值 memo、`EC-SOLVE`；
- `L0`、`L_DFF`、`L_PACK`、`PACK-DEC`、`FT-PORT`、`CBJ`。

v0.9 只加三样，**不删任何开关**：

1. **FBP-LB（分数分箱下界）**：`L_FBP(σ)=min{H : FBP(σ,H)}`。`FBP` 是 `PACK` 的 LP 松弛：配置（任务子集×机器）的使用次数可取分数，任务本身仍不可分。它是 `L_DFF` 与 `L_PACK` 之间的新层。
2. **WEIGHT 叶**：`w≥0, Σw>m, ∀可行配置 S: Σ_{i∈S}w_i≤1` 是 `PACK(σ,H)=NO` 的短证书；作为 `FC-DEC` 的第四条叶规则。
3. **CHECK**：一个确定性多项式时间检查器，验证 `(U,π,P)`；`CHECK` 接受 ⇒ `OPT=U`。这把 v0.8 的 fail-stop 升级为 **fail-checkable**。

关闭三样 → 逐字回到 v0.8。

```text
关闭 FBP-LB + WEIGHT + CHECK   → v0.8 的 X-DUB/IP*
只开 FBP-LB                    → v0.8 搜索 + 多项式、短证书的根下界
只开 WEIGHT                    → v0.8 搜索 + 可检查的节点剪枝
全部打开                       → v0.9 的 X-DUB/FC*
```

## 2. 诊断：v0.8 的 NO 是一张"不可检查的布尔值"

### 2.1 PACK 的两个成本

`PACK(σ,H)` 的精确定义见 v0.8 §3.2。它有两个成本：

- **时间**：m=2 时 `O(nH/word)`；m≥3 时 `O(m^n)` 最坏。
- **证书**：`PACK=NO` 只返回一个布尔值。要独立确认这个 NO，必须重跑整棵 B&B。v0.8 §11.7 明确写了"没有全量 witness checker"。

### 2.2 一个自然的问题

**`PACK=NO` 有没有一个与搜索树无关的短证明？**

考虑整数打包 `α:R→[m]`。它诱导一个分数解：对每台机器 k，令 `S_k=α^{-1}(k)`，`y_{S_k,k}=1`，其余为 0。于是

```text
PACK(σ,H) 可行  ⇒  FBP(σ,H) 可行.
```

反过来不成立。所以 `L_FBP≤L_PACK`。分数松弛通常更弱；但"更弱"不等于"证不出"：如果 FBP 已经不可行，那么 PACK 更不可行，而且 FBP 的不可行性有一个对偶见证。问题变成：**在本 benchmark 的临界层上，FBP 到底可不可行？**

### 2.3 本轮的经验回答

在 50/50 个分区实例的 `H=OPT−1` 上，FBP 不可行；在 80/80 个主基准实例上 `L_FBP=L_PACK`。这不是定理（§10 会讲清楚），但它是本轮全部实验设计的出发点。

## 3. FBP：分数分箱下界

### 3.1 定义

**定义 1（配置）**：给定 `σ=(R,A,est)` 与 H，机器 k 的容量 `C_k=H−A_k`，资格集 `E_k={i∈R : max(A_k,est_i)+p_i+q_i≤H}`。一个配置是二元组 `(S,k)`，满足 `S⊆E_k` 且 `Σ_{i∈S}p_i≤C_k`。

**定义 2（FBP）**：

```text
FBP(σ,H) = ∃ y: {(S,k)} → Q≥0:
  (F1) ∀i∈R:  Σ_{(S,k): i∈S} y_{S,k} ≥ 1
  (F2)        Σ_{(S,k)} y_{S,k} ≤ m
```

`τ*(σ,H)=min Σ y`，不可行记 `∞`；`L_FBP(σ)=min{H : τ*(σ,H)≤m}`。

**与 PACK 的唯一差别**：`y` 可取分数。任务仍然不可分（每个任务整体出现在配置里），所以这不是"可抢占"松弛；被放宽的是 **bin 的使用次数**。

**为什么 (F2) 是 `≤m` 而不是每台机器 `Σ_S y_{S,k}≤1`**：后者更强，但对偶要多一组机器变量 `v_k`，见证不再是单个 w。本轮取 (F2)，它仍是 PACK 的松弛（整数解给 m 个配置），对偶最简单。代价是 LP 可能比机器感知版弱；在本轮实例上没有观察到损失（§9.2）。

### 3.2 对偶权重见证

**定理 1（权重见证）**：若 `w≥0`，`Σ_{i∈R}w_i>m`，且对每个可行配置 `(S,k)` 都有 `Σ_{i∈S}w_i≤1`，则 `PACK(σ,H)=NO`。

**证明**：反设存在整数赋值 `α`。令 `S_k=α^{-1}(k)`。每个 `(S_k,k)` 是可行配置，故 `Σ_{i∈S_k}w_i≤1`。对 k 求和：

```text
Σ_i w_i = Σ_k Σ_{i∈S_k} w_i ≤ m,
```

与 `Σw>m` 矛盾。证毕。

这个证明只用了"m 台机器、每台一个配置、每个配置权重 ≤1"，没有用搜索。`w` 就是证书。

**引理 1（FBP 可采纳）**：`FBP(σ,H)=NO ⇒ DEC(σ,H)=NO`。

**证明**：任一 `Cmax≤H` 的调度诱导整数赋值 `α`（任务 i 在机器 `α(i)` 上），于是 `y_{S_k,k}=1` 满足 (F1)(F2)，`Σy=m`。故 FBP 可行。取逆否。证毕。

**引理 2（单调性）**：H 增大时 `C_k` 与 `E_k` 都单调变宽，配置集合变大，故 `τ*(σ,H)` 单调不增；`L_FBP` 良定义。

### 3.3 层次定理

**引理 3（DFF 权重是可行的对偶）**：设容量统一为 C（根状态 `A=0` 时 `C=H`），`t≥1` 且 `⌊C/t⌋≥1`，定义

```text
w_i = ⌊p_i/t⌋ / ⌊C/t⌋.
```

则对任意配置 S（`Σ_{i∈S}p_i≤C`）有 `Σ_{i∈S}w_i≤1`；且若 `B_t=Σ_i⌊p_i/t⌋ > m⌊C/t⌋`，则 `Σ_i w_i>m`。

**证明**：对配置 S，

```text
Σ_{i∈S}⌊p_i/t⌋ ≤ ⌊Σ_{i∈S}p_i / t⌋ ≤ ⌊C/t⌋,
```

第一式是 floor 的次可加性，第二式用 `Σp≤C`。两边除以 `⌊C/t⌋` 得 `Σ_{i∈S}w_i≤1`。若 `B_t>m⌊C/t⌋`，则 `Σ_iw_i=B_t/⌊C/t⌋>m`。证毕。

**定理 2（层次）**：

```text
max(L0, L_DFF) ≤ max(L0, L_FBP) ≤ max(L0, L_PACK) ≤ OPT.
```

**证明**：

- `L_DFF≤L_FBP`：对任意 `H<L_DFF`，存在 t 使 `H<t·ceil(B_t/m)`。由 `H/t<ceil(B_t/m)` 得 `⌊H/t⌋≤ceil(B_t/m)−1<B_t/m`，即 `B_t>m⌊H/t⌋`。由引理 3，`w` 是 H 处的可行对偶且 `Σw>m`，故 FBP 在 H 处不可行。对所有这样的 H 取上确界，得 `L_FBP≥t·ceil(B_t/m)`；对 t 取 max 得 `L_FBP≥L_DFF`。
- `L_FBP≤L_PACK`：整数解 `y_{S_k,k}=1` 是 FBP 的可行解，故 PACK 可行 ⇒ FBP 可行。
- `L_PACK≤OPT`：v0.8 定理 5。

三者与 `L0` 取 max 仍保持不等式。证毕。

**注**：引理 3 与定理 2 的证明在统一容量下最干净；非统一容量时用 `C_max=max_k C_k` 的保守版本，结论不变但界更弱。本轮主实验（根状态）是统一容量。

### 3.4 求解：配置枚举 + 单纯形（本轮实现）

```text
FBP-SOLVE(σ,H):
1  caps[k] ← H−A[k];  elig[k] ← {i: max(A[k],est[i])+p[i]+q[i]≤H}
2  if ∃i: elig[i]=∅ for all k: return (∞, ⊥)
3  Configs ← 枚举所有 S⊆R 使得 ∃k: S⊆elig[k] 且 Σ_{i∈S}p[i]≤caps[k]
4  τ*, w ← SIMPLEX(Configs, caps)      # min Σy s.t. Ay≥1, y≥0
5  return (τ*, w)
```

第 3 步在 n≤14 时最多 `2^n` 个候选，实测 n=12–13 时一次阈值搜索（2–4 次 LP）5–70 ms（纯 Python，见 §9.6）。第 4 步是标准 primal simplex：初始基为单元素配置，`π=1^T B^{-1}` 是对偶权重，定价扫描所有配置；`π·a>1` 则入基，比值检验出基。浮点实现，最终见证用有理数重构（§3.6）。

**渐近版**：不枚举配置，用列生成——定价子问题是 0/1 背包（容量 `C_k`、资格 `E_k`、价值 `π_i`），`O(n·C_k)` 的 DP；每轮加一个负 reduced cost 列。配置 LP 的分离 oracle 是背包，故 LP 可在 `poly(n,m,log H)` 次 oracle 调用内解出（椭球/列生成），总代价伪多项式于 H。这是 `L_FBP` 相对 `L_PACK` 的渐近优势：m≥3 时 `L_PACK` 的 B&B 是 `O(m^n)`，`L_FBP` 是多项式。

### 3.5 阈值搜索

```text
FBP-LB(σ, lo, hi):
1  if τ*(σ,lo) ≤ m: return lo
2  if τ*(σ,hi) > m: return hi+1
3  a,b ← lo,hi
4  while a<b:
5      mid ← (a+b)//2
6      if τ*(σ,mid) ≤ m: b ← mid
7      else: a ← mid+1
8  return a
```

由引理 2，`τ*` 单调，二分正确。代价 `O(log(hi−lo))` 次 LP。

### 3.6 见证检查与有理化

```text
CHECK-WEIGHT(w, σ, H):
1  if ∃i: w_i<0: reject
2  if Σ_i w_i ≤ m: reject
3  for k in 0..m−1:
4      C ← H−A_k
5      if KNAPSACK(E_k, C, w) > 1: reject      # 0/1 背包，O(nC)
6  accept
```

本轮实现用 `Fraction(x).limit_denominator(120)` 把浮点权重有理化，再用 Fraction 背包精确检查。50/50 个分区实例通过（§9.5）。生产版应直接用精确有理数解 LP，或使用可验证的 LP 证书；本轮只做到"浮点解 + 有理重构 + 精确复检"。

## 4. FC-DEC：把 WEIGHT 放进 DEC

### 4.1 规则

在 v0.8 的 `(D1) 截止期 / (D2) 能量 / (D3) 阈值 memo / (D4) PACK` 之后加：

```text
(D5) τ*(σ,H) > m  ⇒  return NO(WEIGHT, w)
```

`(D5)` 是必要条件（引理 1），只删不可能的分支。**LP 可行时不能返回 YES**：松弛可行不蕴含整数可行，必须继续走 `(D4)`/分支。

### 4.2 伪代码

```text
FC-DEC(σ=(R,A,est), H, memo):
  if R=∅: return YES([])
  if max(A)>H: return NO(DEAD, ⊥)
  est,q ← HEADS-TAILS(σ)
  if ∃i∈R: est_i+p_i+q_i>H: return NO(DEAD, (i, est_i))
  if E(R,A)>H: return NO(ENERGY, ⊥)
  key ← (R,A,est_R)
  if memo.bad[key] ≥ H: return NO(MEMO, key)

  # (D5) 新增：分数分箱
  if T_LP(σ):
      τ,w ← FBP-SOLVE(σ,H)
      if τ > m:
          memo.bad[key] ← max(memo.bad[key], H)
          return NO(WEIGHT, w)

  # (D4) v0.8 的精确整数分箱
  if T_PACK(σ) and not PACK(σ,H):
      memo.bad[key] ← max(memo.bad[key], H)
      return NO(PACK, trace)

  for i in READY(R) sorted by (H−q_i−p_i)−est_i:
      for k in 0..m−1:
          t ← max(A_k, est_i)
          if t+p_i+q_i>H: continue
          A' ← A with A'_k=t+p_i
          est' ← PROPAGATE(est, i, t+p_i)
          r ← FC-DEC(R\{i}, A', H, memo)
          if r=YES: return YES([(i,k,t)]+r.sched)
  memo.bad[key] ← max(memo.bad[key], H)
  return NO(RESOLVE, children)
```

### 4.3 成本控制 `T_LP`

`T_LP(σ)` 为真当且仅当：

- 根调用；或
- `m≥3` 且 `|R|≤κ_LP`（本轮默认 `κ_LP=12`）；或
- `PACK` 的 B&B 预算耗尽（把 LP 当作降级证书）。

m=2 时 `PACK` 是 `O(nH/word)` 的 bitset，通常比 LP 便宜，默认不在节点跑 LP；根上仍跑一次，因为根证书只需要一次。

### 4.4 与 v0.8 的关系

- 关掉 `T_LP`：逐字回到 v0.8 的 `PACK-DEC`。
- 开 `T_LP`：在 LP 不可行的节点上，用 `O(n)` 个数的见证替代 B&B；在 LP 可行的节点上，行为与 v0.8 相同（继续 PACK/分支）。
- 因此 `FC-DEC` 的搜索树是 `PACK-DEC` 的子树；最坏复杂度不变，实际节点数不增。

## 5. FC-SOLVE：把下界当作求解器

```text
FC-SOLVE(σ0)
1  U ← min(CP, LPT, MWKR)(σ0)                 # 三条表调度上界
2  L ← L0(σ0)
3  L ← max(L, L_DFF(σ0))
4  if T_LP(σ0):
5      L ← max(L, FBP-LB(σ0, L, U−1))
6  if L ≥ U: return CERT(U, schedule(U), root-witness)
7  memo ← ∅
8  loop:
9      r ← FC-DEC(σ0, U−1, memo)
10     if r=NO(P): return CERT(U, schedule(U), P)
11     if r=YES(π):
12         U ← makespan(π)          # ≤ U−1 < U，严格下降
13         goto 4
14     if r=? : return v0.8-FALLBACK(σ0, U, L)
```

第 6 行是"根上闭合"：LP 下界已经等于上界，不需要任何 DEC 节点。第 10 行是"搜索闭合"：`FC-DEC` 返回一棵证明 DAG。

**定理 3（FC-SOLVE 正确）**：若 `FC-SOLVE` 返回 `U`，则 `U=OPT(σ0)`。

**证明**：

- `U` 始终来自一条可行调度，故 `OPT≤U`。
- 若在第 6 行返回：`L≥U`，而 `L` 是 `L0/L_DFF/L_FBP` 的 max，每一项 ≤OPT（v0.8 定理 6、定理 2），故 `OPT≥U`。
- 若在第 10 行返回：`P` 是 `FC-DEC(σ0,U−1)=NO` 的证明，由 FC-DEC 的完备性（定理 6），不存在 `Cmax≤U−1` 的调度，故 `OPT≥U`。
- 夹逼得 `OPT=U`。证毕。

**终止性**：第 12–13 行 `U` 严格下降（整数），且 `U≥OPT`，最多 `U0−L0+1` 轮；每轮要么下降、要么返回。

## 6. CHECK：全局最优证书的检查器

### 6.1 证书语法

```text
CERT   ::= (U, π, P)
π      ::= { i ↦ (machine k, start t) }         # 完整调度
P      ::= NO(σ0, U−1) 的证明 DAG
node   ::= LEAF(rule, witness) | RESOLVE(children)
rule   ::= DEAD(i,v) | ENERGY | DFF(t) | WEIGHT(w) | PACK(trace) | MEMO(key)
```

`σ0` 是根状态 `(R=V, A=(0,…,0), est=0)`；每个 `RESOLVE` 结点记录它的 `(R,A,est,H)` 与分支枚举。

### 6.2 检查规则

```text
CHECK(U, π, P):
1  # 原始侧
2  验证 π 覆盖每个任务恰好一次；每台机器上的任务不重叠；
3  每个任务的开始 ≥ 其前驱的完成；makespan(π) = U。
4  # 对偶/搜索侧：递归验证 P
5  VERIFY(P, σ0, U−1)
6  return accept
```

`VERIFY(node, σ, H)` 按规则：

| 规则 | 检查 | 代价 |
|---|---|---|
| `DEAD(i,v)` | 重算 `est_i`，确认 `est_i+p_i+q_i>H` 且 `v=est_i` | O(n) |
| `ENERGY` | `ceil((Σ_R p+ΣA)/m)>H` | O(n+m) |
| `DFF(t)` | `t·ceil(B_t/m)>H` | O(n) |
| `WEIGHT(w)` | `CHECK-WEIGHT(w,σ,H)`（§3.6） | O(m·n·H) |
| `PACK(trace)` | 重放 B&B 反证：每个内部结点的分支必须覆盖所有 `(i,k)`，每个叶必须是 `DEAD/ENERGY/WEIGHT` | O(trace) |
| `MEMO(key)` | 确认 `key` 已在同一证明中作为 `NO(·,H')`、`H'≥H` 出现 | O(1) |
| `RESOLVE` | 子结点恰好是 `(i,k)` 的全部分支；每个子结点 `VERIFY` 通过 | 递归 |

`DEAD` 的 `v` 必须是重算出的 `est_i`，不能由求解器随便填；`WEIGHT` 的 `w` 必须过背包检查；`PACK` 的 trace 必须覆盖所有分支。**检查器不信任求解器的任何中间结论。**

### 6.3 可靠性定理

**定理 4（CHECK 可靠）**：若 `CHECK(U,π,P)` 接受，则 `OPT(σ0)=U`。

**证明**：对 P 的结构归纳，证明每个 `VERIFY(node,σ,H)` 通过 ⇒ `DEC(σ,H)=NO`：

- 叶规则 `DEAD/ENERGY/DFF/WEIGHT` 分别是 v0.8 的截止期界（D1）、v0.8 引理 1（能量）、v0.8 定理 3（DFF）、引理 3 的必要条件；
- `PACK(trace)` 通过 ⇒ 重放的 B&B 覆盖所有分支且每个叶是必要条件 ⇒ `PACK(σ,H)=NO` ⇒ `DEC=NO`（v0.8 引理 4）；
- `RESOLVE` 通过 ⇒ 所有 `(i,k)` 分支都是 NO，且分支枚举覆盖所有可行调度的第一步 ⇒ `DEC(σ,H)=NO`；
- 归纳得 `VERIFY(root,σ0,U−1)` ⇒ 不存在 `Cmax≤U−1` 的调度 ⇒ `OPT≥U`。

原始侧 `π` 是 `Cmax≤U` 的可行调度 ⇒ `OPT≤U`。夹逼得 `OPT=U`。证毕。

### 6.4 根证书的完备性

**定理 5（根证书完备）**：若 `FC-SOLVE` 在第 6 行以 `L_FBP≥U` 返回，则它发出的 `(U,π,w)` 被 `CHECK` 接受。

**证明**：`π` 由表调度给出，合法；`L_FBP≥U` 意味着 `τ*(σ0,U−1)>m`，单纯形在 `U−1` 处返回的 `w` 满足定理 1 的前提；§3.6 的背包检查逐一验证。故 `CHECK` 接受。证毕。

**本轮实现范围**：50 个分区实例全部走根证书路径（定理 5），已实测 50/50 接受（§9.5）。`RESOLVE`/`PACK(trace)` 的检查器已按上表设计并实现了原型，但只在 50 个根证书 + 变异测试上跑过，没有在 DENSE30 的搜索证明上做全量验证。

### 6.5 复杂度

```text
CHECK 时间 = O( |P| · (n + m·n·H) )        # 每个 WEIGHT 叶一次背包
CHECK 空间 = O( |P| + n )                  # 递归栈 + 见证
证书长度   = O( |P| + n · #WEIGHT )
```

对根证书（单个 `WEIGHT` 叶），`|P|=1`，检查是 `O(m·n·H)`；实测 n≤13 时 0.5 ms（Fraction 精确版）/ 30–50 µs（浮点版）。

## 8. 复杂度

### 8.1 单次 FBP

```text
枚举版:  O(2^n · n^2 · I)      # I = 单纯形迭代数，实测 14–30
列生成:  O(poly(n,m,log H) · nH)   # 每次定价 O(nH)
```

### 8.2 `L_FBP`

```text
O(log(U−L0)) 次 FBP 求解.
```

### 8.3 FC-DEC

```text
时间: O( N_dec · (n + m·n·H + T_PACK) )
空间: O( S_dec · (m+n) ) + memo + 证明 DAG
```

`N_dec`、`S_dec` 与 v0.8 同阶；`WEIGHT` 只改变实际节点数，不改变最坏 `O((mn)^n)`。

### 8.4 与 v0.8 的对比

| 对象 | 最坏复杂度 | 证书 |

| v0.9 `L_FBP` | 枚举 `O(2^n·n^2·I)`；列生成多项式 | `n` 个有理数 |
| v0.8 `PACK-DEC` | 指数 | 搜索树 |
| v0.9 `FC-DEC` | 指数（同阶，树更小） | 叶见证 + DAG |
| v0.9 `CHECK` | `O(|P|·m·n·H)` | — |

## 9. 实验

### 9.1 设置

- **DENSE30**：v0.8 的 30 个 `n=9–10, m=2` 困难优先实例，OPT 由独立精确 DFS 给出。
- **PART2**：30 个 `m=2` 纯分箱实例，`n=10–13`，`p_i∈[2,9]`，总加工为偶数，且不存在恰好一半的子集和；`OPT=H+1`。
- **PART3**：20 个 `m=3` 纯分箱实例，`n=9–12`，`p_i∈[2,7]`，总加工为 3 的倍数，且 3-bin 在 `H=总/3` 处不可行；`OPT=H+1`。
- **随机族**：80 个 `n=9–14, m=2/3/4` 随机分箱；400 个 `n=7–11, m=3/4, p∈[2,12]` 分箱。
- **穷举族**：`C∈{8,9,10,12}`、`m∈{2,3,4}`、`n≤8`、总加工 ≤mC 的全部多重集。
- **实现**：纯 Python 3.12，单线程；LP 用浮点单纯形 + 有理重构；时间为单次测量，只用于相对比较。

### 9.2 主结果：层次在主基准上的闭合

**根判定（`H=OPT−1`）**：

| 族 | # | `L0` | `L_DFF` | `L_FBP` | `L_PACK` | 最便宜闭合层 |
|---|---:|---:|---:|---:|---:|---|
| DENSE30 | 30 | 23 | 19 | 23 | 23 | L0 23，无 7 |
| PART2 | 30 | 0 | 11 | **30** | 30 | DFF 11，FBP 19，PACK 0 |
| PART3 | 20 | 0 | 9 | **20** | 20 | DFF 9，FBP 11，PACK 0 |

三个结论：

1. **`L_FBP` 在 50/50 个分区实例上闭合**，而 `L_DFF` 只有 20/50。**30 个实例是"DFF 不行、FBP 行"**——这正是 v0.8 需要 B&B 的那一批。
2. **`PACK` 从来不是"最便宜的闭合层"（0/50）**：20 个用 DFF、30 个用 FBP。v0.8 的指数 B&B 在根上被多项式 LP 完全替代。
3. **`L_FBP = L_PACK` 在 80/80 个实例上成立**（50 分区 + 30 稠密）。在 57 个 `L0<OPT` 的实例上，LP 闭合 50 个；失败 7 个，全部是 DENSE30 的优先/关键路径间隙。

> 注意：50 个分区实例的 `L0=OPT−1`，所以 `L_FBP` 与 `L_PACK` 的相等部分是"二分区间只有两层"造成的；真正有信息量的是 **LP 在 `OPT−1` 上不可行**（50/50）。DENSE30 的 7 个间隙实例上两者都停在同一个低于 OPT 的值，这也不是"LP 恰好等于 PACK"的构造，而是实测。

### 9.3 分数超出量、支撑、紧配置

**`τ*(OPT−1)−m`（LP 离可行有多远）**：

| 族 | 最小 | 最大 | 均值 |
|---|---:|---:|---:|
| PART2 | 0.056 | 0.200 | 0.088 |
| PART3 | 0.083 | 0.500 | 0.189 |

LP 是"刚刚好"不可行：超出量只有 1/18 到 1/2 个 bin。整数间隙正好落在这条细缝里。

**对偶见证的结构（dependency analysis）**：

| 族 | `supp(w)/n` | 紧配置数（权重恰为 1） |
|---|---|---|
| PART2 | 0.92–1.00 | 2–797 |
| PART3 | 0.64–1.00 | 12–314 |

这是一个**负结果**：`WEIGHT` 证书短在"数值个数"（n 个有理数），但不短在"依赖结构"——支撑几乎是满的，紧配置成百上千。不要指望用它做小核、回跳或局部解释。它与 v0.8 的"MIS 核是全局的"负结果同构。

**读集阶梯**：

| 层 | 见证 | 读集 | 长度 |
|---|---|---|---|
| `L0` | 一个 max | `A, est_i` | O(1) |
| `L_DFF` | `t, B_t` | `{p_i}` | O(1) |
| `L_FBP` | `w` | `R, A, est` | O(n) |
| `L_PACK` | B&B trace | 全状态 | Θ(搜索) |

**证书强度是用读集换来的**；本轮把这条阶梯从"哲学"变成了可测量的表。

### 9.4 间隙搜索：随机 + 穷举

问题：**存在"LP 可行、整数不可行"的实例吗？** 若存在，`L_FBP < L_PACK`，短证书不够用。

| 实验 | 规模 | 结果 |
|---|---|---|
| 随机分箱，`H=OPT−1` | 80 个（n=9–14, m=2/3/4） | LP 不可行 80/80 |
| `frac_lb` vs `bin_opt` | 400 个（n=7–11, m=3/4） | `L_FBP=OPT` 400/400 |
| 全多重集穷举 | `C∈{8,9,10,12}`, `m∈{2,3,4}`, `n≤8` | 无"整数不可行、LP 可行"实例 |
| 主基准 | 50 个 | `L_FBP=L_PACK` 50/50 |

合计 **530 个实例 + 小规模穷举**，没有找到严格间隙。

**但这不能当成定理。** FBP 是 PACK 的松弛，`L_FBP≤L_PACK` 恒成立；若在所有实例上取等，则分箱可在多项式时间内精确求解（LP 阈值 + 二分），与 P≠NP 矛盾。所以**严格间隙实例必然存在**，只是本轮的 n≤14、unary 规模、以及"临界层"这个特定位置没有撞到。本轮把它列为最大的经验风险（§11.1），而不是结论。

### 9.5 证书检查与变异测试

对 50 个分区实例，构造完整证书 `(U, π, w)`：

- `π`：由精确 B&B 给出的最优装箱，转成 m 台机器上的顺序调度；
- `w`：`H=U−1` 处的 LP 对偶，`limit_denominator(120)` 有理化。

| 测试 | 结果 |
|---|---|
| 证书被 `CHECK` 接受 | **50/50** |
| 有理化后精确背包复检 | **50/50** |
| 故意过载/漏任务/重复任务 | **500/500 拒绝** |
| 权重单坐标 +0.02（破坏可行性） | **500/500 拒绝** |
| 随机权重向量（Σ>m 但非可行对偶） | **500/500 拒绝** |
| 随机移动一个任务（可能仍可行） | 481/500 拒绝；19 个仍是合法调度，不算错 |

`CHECK` 时间：浮点版中位 28–48 µs，Fraction 精确版中位 0.51 ms、最大 1.18 ms（n≤13）。

### 9.6 扩展性 pilot

固定 `m=3`、精确体积 `H=总/3`、整数不可行的实例，比较 v0.8 的 B&B 与本轮 LP：

| n | B&B 节点（中位） | LP 迭代（中位） | LP 时间（中位） |
|---:|---:|---:|---:|
| 9 | 43 | 14 | 1.4 ms |
| 10 | 54 | 16 | 2.6 ms |
| 11 | 338 | 18 | 4.4 ms |
| 12 | 509 | 20 | 8.6 ms |
| 13 | 650 | 24 | 17.5 ms |
| 14 | 2,819 | 27 | 36.5 ms |

n 从 9 到 14：B&B 节点 ×65，LP 迭代 ×1.9，LP 时间 ×26。方向是对的（多项式 vs 指数），但**在 n≤14 上 LP 的绝对墙钟仍比 bitset/B&B 慢**（枚举版 `2^n` + 纯 Python 单纯形）；n=14 只有 2 个样本，不能外推。列生成版没有实现，这是 §10.6 的边界。

### 9.7 DENSE30 的 7 个缺口

7 个根在 `H=OPT−1` 上没有任何层能闭合（`L0, L_DFF, L_FBP, L_PACK` 四者都 `<OPT`）。它们是优先/尾长导致的不可行，容量松弛看不到。`FC-DEC` 仍要跑；v0.8 的实测是这 7 个里 3 个有 PACK 收益（653→575、299→109、123→81），其余 4 个 PACK 零收益（base 173/305/471/1455 不变）。LP 对它们没有增益，这与"FBP 只保留容量、丢掉优先"的定位一致。

## 10. 负结果与边界

1. **LP 是松弛，严格间隙必然存在**：本轮 530 个实例没找到，但 P≠NP 蕴含它存在。`L_FBP=L_PACK` 是经验事实，不是定理。
2. **LP 在 n≤14 上更慢**：枚举版 `2^n` + 纯 Python 单纯形，比 v0.8 的 bitset/B&B 慢 1–2 个数量级；渐近优势要 n≥20 才可能兑现，本轮没有数据。
3. **对偶见证没有小支撑/小核**：`supp(w)` 几乎满，紧配置 2–797 个；dependency analysis 在"压缩证书"上没有收益，只在"读集阶梯"的解释上有收益。
4. **DENSE30 的 7 个缺口不动**：容量松弛对优先/尾长不可行无能为力；这是 v0.7 就存在的边界。
5. **m=2 时 PACK 已经是多项式**：LP 只带来证书变短（n 个数 vs bitset DP 表），不带来渐近收益；真正受益的是 m≥3。
6. **列生成版未实现**：本轮所有 LP 都是配置枚举，n≤14；`O(poly(n,m,H))` 的渐近声明只有算法描述，没有对应实现与计时。
7. **全量 proof-DAG checker 未验证**：`RESOLVE`/`PACK(trace)` 的检查规则已设计并写了原型，但没有在 DENSE30 的搜索证明上做全量重放；50 个根证书是实测的。
8. **浮点 LP + 有理重构**：`limit_denominator(120)` 在 50 个实例上都成功，但不保证对所有实例成功；生产版需要精确有理 LP 或可验证的浮点证书。
9. **时间为单次纯 Python**：不能当作稳定常数；LP 时间随 H、n、单纯形迭代数波动。
10. **没有 n≥15、m>3 优先实例、PSPLIB**。

## 11. 已知风险

1. **经验等式的选择偏差**：50 个分区实例是**按 `L_PACK=OPT` 构造**的；它们恰好也是"LP 在 OPT−1 不可行"。真实实例若有容量松弛，LP 可能可行而整数不可行，短证书就没了。这是最大风险。
2. **严格间隙实例的存在性**：由 P≠NP，必然存在 `L_FBP<L_PACK` 的实例；本轮没有给出一个具体构造，也没有给出间隙上界。没有这个构造，"LP 替代 B&B"就只是 benchmark 结论。
3. **LP 的常数**：配置枚举 + 单纯形在 n≤14 上比 B&B 慢；列生成的工程实现没有做，真实加速比未知。
4. **`τ*` 的数值可靠性**：浮点单纯形可能早停或抖动；虽然有精确复检兜底，但复检失败时只能退回 PACK，性能会退化。
5. **`CHECK` 的完备性只在根证书上验证**：`RESOLVE` 的分支覆盖检查在实现上容易出错（机器身份、`est` 重算、跳过分支的 deadline 归一化），需要形式化的单元测试。
6. **对偶退化**：紧配置成百上千，说明 LP 最优面很平；不同的 `w` 可能给出不同长度的有理表示，证书长度不稳定。
7. **与 v0.8 的 `L_PACK` 数值相等是经验事实**：若某个真实实例上 `L_FBP<L_PACK`，`FC-SOLVE` 的根闭合会退化为 DEC，性能回到 v0.8 的指数路径（正确性不受影响）。
8. **`PACK` 的 trace 证书仍可能是指数的**：短证书只覆盖 LP 不可行的情形；LP 可行而整数不可行时，证书必须包含搜索，长度 Θ(搜索)。
9. **没有 Byzantine 的完整防御**：`CHECK` 能抓住"见证不合法"，但如果检查器本身有 bug，仍然会接受错证书；本轮只做了变异测试，没有形式化验证检查器。
10. **时间/规模外推**：n≥15、m>3 优先实例、真实 RCPSP 全部未做。

---

## 12. 一句话最大风险

**50/50 的闭合依赖"临界层 H=OPT−1 上 LP 恰好不可行"这一经验事实；LP 是松弛，理论上必有严格间隙实例，一旦撞上，短证书消失，DEC 仍退回指数搜索。**
