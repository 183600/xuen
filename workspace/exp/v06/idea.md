# 想法区 · 第 8 轮：从 X-DUB/AG* 到 X-DUB/TQ*

**灵感词**：确定性算法 / 近似算法 / 计算几何  
**起点**：v0.5「X-DUB/AG*」。它已经有 A* 的路径最大下界 `F`、focal + 贪心 guide、THRESH 阈值证书、同 `S` 支配和证明 DAG。本轮不推翻这些，只补三个更基础的结构性缺口：**窗口证书只用了“完全被迫”的任务、状态商取得太细、近似只停留在启发式**。

## 一句话直觉：窗口不是矩形，是帐篷；只取“完全被迫”的任务，等于只取帐篷的平顶

v0.5 的 THRESH 对固定窗口 `[a,b)` 和候选截止期 `H` 做：

```text
X_H = { i : lo_i ≥ a 且 H - q_i ≤ b }
若 BP(X_H, caps) 不可行，则 H 不可行
```

这要求任务**完全**落在窗口里：`lo_i ≥ a` 且完成期限 `H-q_i ≤ b`。但一个任务只要与窗口有交叠，就对窗口内的机器容量有“强制占用”。把任务 i 的最早开始记为 `est_i`、最晚完成记为 `H-q_i`，它在窗口 `[a,b)` 内的强制处理量是

```text
e_i(a,b;H) = max(0, p_i - max(0, a-est_i) - max(0, H-q_i-b)).
```

这个函数在 `(a,b)` 平面上是一个**帐篷**：中间平顶是 `p_i`（任务完全被迫在窗口里），两条斜边是部分交叠，外面是 0。v0.5 只取了平顶 `e_i=p_i`，把斜边全扔了。斜边恰恰是低截止期、紧窗口时最有信息的部分。

更强的证书因此是：

```text
items = { e_i(a,b;H) : i∈R, e_i>0 }
caps_k = max(0, b - max(a, A_k))
若 BP(items, caps) 不可行，则不存在 makespan ≤ H 的完成。
```

为什么这是对的？取任意一条 makespan ≤ H 的完成调度。任务 i 在窗口内的那一段是 `[s_i, s_i+p_i) ∩ [a,b)`，长度至少是 `e_i`；它落在任务所在的机器上，且同一台机器上的这些段互不重叠。把每段缩到 `e_i`，就得到 `items` 到 `caps` 的一个可行装箱。所以“装箱不可行”蕴涵“调度不存在”。这是一个**单边近似**：它可能漏掉真正的不可行（假阴性），但绝不会把可行误判为不可行（无假阳性）。换句话说，**近似的是不可行区域，不是答案**；近似误差只会让下界变弱，不会让搜索剪错。

这个观察把 THRESH 从“点证书”升级成“区间证书”：

- 固定 `(a,b)`，`e_i` 随 `H` 单调不增（`H` 越小，最晚完成越早，强制段越长），所以 `BP` 不可行性对 `H` 向下封闭；
- 可以二分求 `H*(a,b) = max{H : BP(items(H),caps) 不可行}`；
- 一张证书覆盖所有 `H ≤ H*(a,b)`，给出 `L_TENT = max(L0, max_{a,b}(H*+1))`。

这和 v0.5 的 THRESH 是严格的包含关系：完全被迫的任务有 `e_i=p_i`，部分任务只会增加非负的 item；所以同一个窗口上，TENT 能证的 THRESH 一定能证，反过来不成立。用一个三任务例子可以看出严格性：

```text
m=2, p=(6,6,6), est=(2,2,0), q=(0,0,0), H=10, 窗口 [2,10)
caps=(8,8)
THRESH: 任务 1,2 完全被迫，items=(6,6) -> 可装进 (8,8)
TENT:   任务 3 的部分强制 e=6-(2-0)=4，items=(6,6,4) -> 装不进 (8,8)
```

而 `H=10` 确实不可行：两个 `est=2` 的 6 工时任务必须占满 `[2,8)` 的两台机器，`est=0` 的任务无论放哪台都会与其中一个重叠。`L0=9`，THRESH 停在 9，TENT 能推到 10。这个例子很小，但它说明“部分强制”不是装饰，而是 THRESH 缺失的那一半。

## 第二个缺口：状态商 `(R,A,est)` 比 `(S,A,c)` 更粗，也更正确

v0.5 的支配是：同一个已调度集 `S` 下，`A` 逐分量更小、`c` 逐分量更小。这个条件太细。未来只通过“剩余任务的最早开始”与已调度部分发生关系：

```text
est_i = 已调度前驱的完成时间与剩余前驱链共同决定的最早开始
```

只要 `A` 和 `est` 逐分量不大于对方，任何从对方出发的动作序列，搬到己方都会每一步都不晚。因此

```text
σ ⪯_Q τ  iff  A_σ ≤ A_τ 且 est_σ,i ≤ est_τ,i (∀i∈R)
```

是可靠的，而且 `c` 支配蕴涵 `est` 支配，反过来不成立。几何上，这把状态映射成势空间 `(A,est_R)` 里的一个点，支配就是**正交象限查询**，非支配集就是 Pareto 天空线。v0.5 的 `c` 支配是在一个更细的空间里做同一件事，会漏掉“`c` 不同但 `est` 相同”的等价状态。

理论上这是严格更强的剪枝；实验上却有一个诚实的负结果：在 v0.5 的 AVAIL 点测试已经开启后，30 个困难实例上 `c` 支配是 200 次扩展，`est` 支配是 195 次（1 胜 29 平 0 负）。也就是说，**大部分“c 不同但 est 相同”的状态已经被 AVAIL 提前剪掉了**。这个改动的价值主要在状态表示、证明和 TENT 的接口，而不是节点数。这个负结果本轮照实报告，不把它包装成主卖点。

## 第三个缺口：近似算法应该近似“证书”，而不是近似“答案”

v0.5 的 focal/guide 是启发式，但没有近似保证；v0.6 把“近似”拆成两层：

1. **证书的近似（TENT）**：用独立 item 的装箱去近似“窗口内精确可行性”。它是单边的、可检查的、确定性的；近似误差只让下界变弱，答案仍然精确。
2. **支配的近似（δ-dominance）**：`A_σ ≤ A_τ+δ`、`est_σ ≤ est_τ+δ`。单次替换有引理 `OPT(σ) ≤ OPT(τ)+δ`（把 τ 的最优调度整体右移 δ 即可）。若不做预算，多次替换的 δ 会累积，最坏情况没有 `(1+ε)` 保证；把预算 `b` 并入状态、每次替换扣 δ、并用 `B=⌊εL0⌋` 限制总误差，才能得到确定性的 `U ≤ OPT+B ≤ (1+ε)OPT`。本轮实现了朴素的 δ 模式做实验：30 个实例上 141 次扩展，反而略高于精确的 139 次（k=27 从 25 降到 20，k=29 从 30 升到 37）。结论是：**近似支配不是当前瓶颈**；默认应关闭，保留为大规模/ anytime 的旋钮。

## 实验带来的三个意外

第一，**TENT 的收益集中在根节点**。30 个困难实例上，根下界 `L0` 总和 683，v0.5 THRESH 691，TENT 697；TENT 对 THRESH 是 30/30 不劣、5/30 严格更好；TENT 达到 OPT 的有 29/30，THRESH 是 25/30。根下界只多 6 个单位，但搜索扩展从 195 降到 139（6 胜 24 平 0 负，28.7%），因为多出来的 1–2 个单位正好落在最难的几个实例的根上，直接把“还要证一层”变成“根上就闭合”。

第二，**真正起作用的是“部分 item”，不是“更多窗口”**。把 TENT 的 item 放回 v0.5 的旧窗口族，根下界总和是 695；换成完整的 `(a,b)` 窗口族是 697。完整窗口族只在 2/30 个实例上再加 1–2 个单位。所以几何的贡献首先是**帐篷的斜边**，其次才是二维窗口扫描；这也解释了为什么 v0.5 的 THRESH 已经不错，却仍会在低截止期上漏掉部分强制量。

第三，**简单的“链容量”证书被 L0 支配**。我曾以为“一条优先链上的强制段总和不能超过窗口长度 `b-a`”能抓优先约束 gap；在 78 个随机状态上，它 0/78 严格优于装箱，62/78 严格更弱，且总和恰好等于 `L0`。原因是 `L0` 的最长链已经用了完整工时，窗口内的截断反而更松。这个负结果说明：**precedence gap 不是“某条链在窗口内装不下”这么简单**；要抓它，需要更强的顺序/机器耦合松弛，而不是再加一个链和。

## 本轮方案：X-DUB/TQ*

在 v0.5 上做四处增量：

1. **Q-STATE / Q-DOM**：搜索状态从 `(S,A,c)` 换成 `(R,A,est)`；支配用 `A` 与 `est` 的逐分量序；证明模拟引理；保留 `F` 继承与 focal。
2. **TENT-CERT**：固定窗口的强制段 `e_i`，做精确装箱；二分 `H*(a,b)`；一张证书覆盖 `H≤H*`；根节点/周期扫描启用，点测试可选。
3. **TENT-POINT**：在 `H=U-1` 上额外跑一次 TENT 装箱；实验只多剪 2/139 个节点，作为可选层。
4. **EPS-DOM**：`δ`-支配的单次引理与预算化 `(1+ε)` 设计；朴素模式实验无收益，默认关闭。

组合下界：

```text
L_X6(σ) = max( L0, L_D, L_AV, L_TH, L_TENT )
F(σ)    = 路径上所有 L_X6 的最大值
f(σ)    = max( C(σ), F(σ) )
```

因为同一窗口上 `L_TENT ≥ L_TH`，且 `F` 取路径最大，所以 `L_X6 ≥ L_X5`；关闭 TENT/Q-DOM 就回到 v0.5 的搜索语义。

## 本轮要验证的命题

1. **TENT 可靠**：任意可行完成在窗口内的段长 ≥ `e_i`；这些段诱导一个 `items → caps` 的可行装箱；所以装箱不可行 ⇒ H 不可行。
2. **TENT 单调**：固定 `(a,b)`，`e_i` 对 `H` 单调不增；`BP` 不可行对 `H` 向下封闭；`H*` 的二分合法。
3. **TENT 包含 THRESH**：同一窗口下，THRESH 的 item 是 TENT item 的子集；TENT 检测到所有 THRESH 检测。
4. **Q-DOM 可靠**：`A`/`est` 逐分量更小 ⇒ 任意动作序列的模拟不晚 ⇒ `OPT` 不大于。
5. **Q-DOM 包含 c-DOM**：`c` 逐分量更小 ⇒ `est` 逐分量更小；反之不成立。
6. **δ-DOM 单次可靠**：`OPT(σ) ≤ OPT(τ)+δ`；预算化后可把总误差限制在 `B`。
7. **搜索仍精确**：剪枝只用可采纳的 `f`；guide 只排序；Q-DOM 只删不优状态；终止时 `U=OPT`。
8. **实验收益**：30 个困难实例上 `Q+TENT` 的扩展数应显著低于 `Q`；所有变体的 `U` 必须等于独立 DFS 的 OPT；TENT 不能产生假证书。

## 初步结果与边界

- **根下界**：30 个困难实例，`L0` 总和 683，THRESH 691，TENT 697；TENT≥THRESH 30/30，严格 5/30；TENT=OPT 29/30，THRESH=OPT 25/30；装箱测试 965 → 3135，总耗时约 0.02 秒（纯 Python，30 个实例）。
- **搜索**：同一 harness 下，`c` 支配 + AVAIL 是 200 次扩展，`est` 支配 + AVAIL 是 195 次，`est` + 根 TENT 是 139 次，再加 TENT-POINT 是 137 次。`est` + 根 TENT 对 `est` 是 6 胜 24 平 0 负；对 `c` 支配是 6 胜 24 平 0 负（总计少 30.5%）。所有变体 30/30 返回 OPT。
- **逐实例**：k=6 从 3→1，k=11 从 38→11，k=13 从 1→0，k=14 从 8→5，k=19 从 7→2，k=27 从 43→25（加 TENT-POINT 23），k=29 从 30→30（根下界 34，OPT=35，容量证书关不上最后 1 个单位）。
- **窗口消融**：TENT 用旧窗口 695，用完整窗口 697；完整窗口只在 k=27、k=29 上各加 1。
- **状态级**：78 个随机可达状态，`L0` 总和 1685，THRESH 1872，TENT 1912；TENT≥THRESH 78/78，严格 30/78；装箱测试 3149 → 10291。
- **验证**：40 个随机实例、118 个 TENT 声明，逐一用独立的有界 DFS 检查，0 个假阳性；60 个新鲜 n=9 实例上 TENT 从不超过 OPT；其中只有 3 个实例 `L0<OPT`，TENT 在 1/60 上严格优于 THRESH，0/60 更差。
- **近似**：δ=1 的朴素支配 141 次（k=27 25→20，k=29 30→37），相对精确 139 次无净收益；单次替换引理成立，但全局 `(1+ε)` 需要预算化状态，本轮未实现。
- **负结果**：链容量证书在 78/78 个状态上不优于 TENT 装箱，62/78 严格更弱，总和等于 L0；周期 TENT 在 n≤10 上没有触发（节点数 <40），留给更大规模。
- **边界**：m=2、n=9–10、30 个筛选出的困难实例；没有 PSPLIB、没有 m>2 的精确装箱、没有独立 proof-DAG checker、没有 n≥20 的 anytime 曲线。时间只用于相对 sanity check。

## 本轮的一句话最大风险

**TENT 的收益集中在根节点、低截止期、容量–截止期耦合的困难尾部；在 precedence-heavy 或 m>2 的大实例上，窗口枚举与精确装箱的成本可能超过它省下的节点，而它对纯顺序 gap（k=29 的 L=34 vs OPT=35）仍然无能为力。**
