## 1. 直觉与动机

**灵感 1（痛点分析 → 评测即分布：训练窄、测试宽）**
直觉：官方把 3.2 万条成功演示全部放在标称场景里，而计分的 320 次真机评测（32 任务 × 10 次）每一次都在 5 类泛化轴上偏离标称场景——**这是一场「训练分布 vs 评测分布」的错位考试**。痛点地图（§2）指出三个最痛处：(a) 泛化缺口是全局乘性损失，同时压低全部 32 任务；(b) 接触丰富任务族（插/拔充电器、插/拔网线、拉链、注射器移水、倒药、解锁等，约 6–8 项）在无触觉输入下对纯开环 chunk 策略近乎结构性失分；(c) 180s 硬上限 + 步骤分意味着「卡死 = 双输」：既丢成功率又丢步骤分，失败恢复与时间管理是被多数队伍忽略的免费分。核心反直觉点：**通才赛道上「最弱任务」和「最险场景」支配平均分——均匀用力的训练是最差策略。**

**灵感 2（伦理审查 → 人机同场评测中，合规本身就是得分面）**
直觉：五类泛化中「人为干扰」官方明写真人进场移动物品；接口文档明写官方会用延迟变异性与动作统计规律评估可信度。伦理审查在赛事语境下落为三件可执行的事：(a) **人在环安全**：人手在执行域内时的降速/停持不是美德而是策略输入与得分前提；(b) **评测诚信红线**：不得（也拿不到）评测现场数据做在线适应，一切泛化手段必须在赛前用公开数据完成；(c) **动作健康度**：输出动作的界内性/平滑性/统计正常性是一等发布门禁，避免触发官方可信度标记。核心反直觉点：**把人手干预当纯噪声是错的——它是五轴中唯一有明确触发信号的场景：检测到手 = 检测到「世界被外力改写」，正确反应是让位→重估→续做，处理得当反而是得分机会。**

**灵感 3（应用落地 → 自部署 API 是第二赛场）**
直觉：赛事明确「平台不提供算力、选手自部署」，N 台机器人 = N 端口并发、每步延迟被记录。模型再好，服务抖动/端口阻塞/episode 状态串扰会直接毁掉一轮评测。落地视角给出硬约束：**延迟稳定性 > 平均延迟 > 模型大小**。同时官方免费的单任务测试通道是唯一真机沙盒，应把它制度化成「诊断-迭代」回路（实验设计见产物区）。核心反直觉点：**接口元数据本身就是模型设计空间**——`obs_delta_indices`（喂什么历史：给干预检测与进度估计提供证据链）、`image_resize`（带宽 vs 感知精度）、`action_chunk_size`（开环吞吐 vs 反应性）是三个大多数人会照抄示例的旋钮，而它们恰恰是「人为干扰鲁棒性 × 延迟确定性 × 180s 时间预算」的权衡枢纽。

**三者统一**：痛点分析回答「分数从哪里丢」，伦理审查划定「什么不能做 + 人机接口怎么做」，应用落地决定「工程上怎么活下来」。三者收敛为一个参赛框架：**官方基线为底座 + 计分轴对齐的数据引擎 + 人机干预感知 + 确定性低延迟服务**（创新点清单 I1–I8，见产物区；本轮为清单 v1，后续轮次只做深化与修剪）。

## 3. 研究问题（本轮立项 Q1–Q5）

- **Q1（增广的几何一致性）**：背景/干扰物/外观增广如何保证「视觉变了、动作语义不变」？位置泛化的轨迹变换（ee 空间刚体变换）与图像域增广如何解耦而不破坏因果？
- **Q2（诊断→加权）**：如何用单任务通道把失败模式聚类成「任务族」，并把族级失败率转成采样权重而不伤强任务（梯度冲突控制）？
- **Q3（干预感知的最小充分信号）**：手部检测 + obs 历史栈能否在 <100ms 内判别「世界被外力改写」？让位-重估-续做状态机如何不与 180s 预算冲突？
- **Q4（伺服回退的规则边界与触发条件）**：通才 chunk 策略 + 几何伺服校正器是否仍算「单模型」（PR2 边界，需向组委会求证）？若可，chunk↔伺服的触发滞回如何设计才不引入模式抖动？
- **Q5（延迟确定性）**：共享 backend 下 N 端口并发，如何把 p99 延迟与动作统计压进官方可信度评估的安全区（量化/编译/预取/批处理/元参数的联合取舍）？

## 4. 设计原则（本轮新立 PR1–PR4）

- **PR1 计分轴对齐律**：每一个训练/增广/推理决策必须指明作用于哪条计分轴（5 类泛化 × 步骤分 × 180s）；指不出的不做。
- **PR2 单模型边界律**：参赛实体 = 一个策略服务；服务内模块化（检测器/伺服/状态机）合规，但「按任务切换不同模型/权重」违规；边界模糊处先求证再实现。
- **PR3 干预安全律**：检测到人手在执行域内 → 立即降速/停持并重估场景；任何「继续执行」必须以「人手已离开 + 场景重估完成」为前提；停持与让位动作本身必须界内平滑（伦理与可信度双重要求）。
- **PR4 部署预算律**：p99 单步延迟与动作健康度是发布门禁；任何模型改动先过本地 stub（run_client）+ 延迟基准，再上真机通道。

## 0. 创新点清单（每点：动机 / 与现有方案差异 / 技术可行性 / 所需资源 / 落地步骤 / 风险）

### I1 五轴泛化数据增广引擎 ★★★★★
- **动机**：计分的 320 次真机评测每次都在 5 类泛化轴上偏离训练分布（F2/F4），泛化缺口是全局乘性损失（P2）。
- **与现有方案差异**：直接 SFT 官方数据的队伍默认「训练分布 = 评测分布」；本点把评测计分轴显式搬进训练分布——背景替换、干扰物注入、未见物品外观迁移、位置重排四条增广流水线，分别对准泛化轴 2/3/4/1（人为干扰轴交给 I4）。
- **技术可行性**：高。LeRobot 数据 4 相机 + 状态齐全（F4）。①背景/干扰物：分割 + inpainting/复制粘贴，仅改图像、动作不变（非接触区域）；②未见物品：同类物体 HSV/纹理/形状域变换或物体库替换；③位置泛化：「技能段重组」——把官方轨迹拆成抓取段/转运段/放置段，按新目标位姿对 ee 空间轨迹做刚体变换重拼接（需限制变换幅度在训练支撑邻域内）。
- **所需资源**：SAM/Grounded-SAM + inpainting（1×A100）；32k eps 离线增广一次 ≈ 2–3 GPU 天；磁盘 ≈ 2TB。
- **落地步骤**：①每任务抽 50 eps 做增广视觉 QA 门禁；②先上背景/干扰物两轴（零动作风险）；③外观/位置两轴小规模验证后放量；④标称:增广 = 1:0.5 起步调参；⑤分轴消融：每轴单独开，用单任务通道真机抽测。
- **风险**：伪影破坏感知（缓解：QA 门禁 + 增广一致性损失）；位置重拼接产生物理不可行动作（缓解：段内变换 + 幅度上限）。

### I2 弱任务诊断-加权课程共训 ★★★★★
- **动机**：单模型平均分被最弱任务支配（P1/F1）；接触丰富族是结构性洼地。
- **差异**：均匀混训把容量浪费在已会任务上；诊断先行、族级加权、梯度冲突受控。
- **可行性**：高。官方提供全参/LoRA/action-expert 微调代码（F6）；单任务通道免费提供诊断数据（F8）。
- **资源**：LoRA 微调 6B 底座 ≈ 4–8×A100 数天；全参 action expert ≈ 8–16×A100。
- **步骤**：①官方 Base + LoRA 全量 32 任务数据首轮训练；②单任务通道跑诊断矩阵（优先预约高价值任务族）；③失败模式聚类成任务族（接触丰富/长程/双臂协调）；④按 1/(族成功率) 软加权采样 + PCGrad 防冲突 + 强任务下限保护；⑤与 I8 同步进入「诊断-加权-重训」循环。
- **风险**：加权过猛伤强任务（缓解：软加权 + 下限）；真机诊断排期不可控（缓解：先在留出 eps 上做离线任务级验证）。

### I3 接触任务族关键点视觉伺服回退 ★★★★
- **动机**：无触觉输入（F8），插/拔/拉链/倒液类任务的最后几厘米对开环 chunk 必然漂移（P4）；该族约占 1/4–1/5，从 ~0% 拉到 30% 可拉动总平均 6–8 个百分点。
- **差异**：纯通才策略是唯一动作来源；本点让通用 chunk 策略负责接近段、几何伺服负责接触段——同一策略服务内的混合推理路径（PR2 边界待向组委会确认，这是最大前提）。
- **可行性**：中。`ee` 控制空间 + per-step 调用天然支持；关键点（插孔/拉链头/杯口）可用开放词汇检测（GroundingDINO/DINOv2）零训练起步；触发器 = 阶段分类器或简单距离门控 + 滞回。
- **资源**：工程为主（1–2 人周/任务族）；GPU 开销小。
- **步骤**：①规则边界求证；②单任务通道在 PlugCharger 上 A/B；③扩展至 PlugInEthernet / ZipUp 族；④触发滞回 + 低置信即回退通才路径（防模式抖动）。
- **风险**：规则边界解释（最大风险）；关键点检测在未见物品轴下漂移（缓解：多假设 + 置信门控，失败即回退）。

### I4 人手干预感知门控 + 自适应 chunk ★★★★
- **动机**：人为干扰轴官方明写真人临时移动物品（F2）；无干预感知的策略对着新现实重复旧动作（P3）；同时 chunk 开环长度直接决定被干预后的反应速度（P5）。
- **差异**：多数队伍把人手当纯噪声；本点把「手的出现」当作「世界被改写」的事件信号（PR3），并据此动态调节 `action_chunk_size`——刚被干预 → 短 chunk 提反应性；环境稳定 → 长 chunk 提吞吐、减延迟暴露。
- **可行性**：高，近零训练成本。手部检测（MediaPipe/YOLO-hand）+ `obs_delta_indices` 历史栈（运动不连续证据，元参数即证据链）；状态机 INTERFERED → 停持 → 场景重估 → 续做，外挂在 get_action 外层、不侵入模型。
- **资源**：1 个轻量检测器（CPU/GPU 均可）+ 1 人周工程。
- **步骤**：①检测器在数据集视频上标定误检率；②状态机接入；③单任务通道验证人为干扰场景；④误检致冻结率 <2%、检测延迟 <50ms。
- **风险**：误检 → 频繁冻结丢 180s 预算（缓解：滞回 + TTL + 冻结时长上限）。

### I5 步骤分导向失败恢复 ★★★
- **动机**：超时 = 失败但步骤分仍计（F3）；「卡死」是成功率与步骤分双输，恢复行为是免费分（P1/P5）。
- **差异**：SFT 策略卡住时输出重复抖动；本点加「进度感」（进度估计头，对齐官方得分点的里程碑标签）+ 卡滞检测（进度导数 < ε 持续 k 步）→ 触发回退原语（后撤-重接近-重抓）。
- **可行性**：中。进度头可在官方数据上自监督/弱监督训练；恢复原语从数据挖掘 retry 段或脚本化原语。
- **资源**：1×GPU 训进度头；1–2 人周工程。
- **步骤**：①里程碑标签定义；②进度头训练；③卡滞判据 + 每 episode 恢复次数上限；④真机 A/B。
- **风险**：恢复动作引入新分布（缓解：原语限制在训练支撑内）；误触发打断正常执行（缓解：滞回 + 次数上限）。

### I6 确定性低延迟部署服务 ★★★★
- **动机**：N 端口并发 + 官方记录每步延迟与动作统计（F5），一次服务抖动毁掉一轮评测（P6）。
- **差异**：最简部署是单实例单端口（官方也承认显存装不下 N 份模型需共享）；本点把 serving 当一等工程：共享 backend + 每端口独立队列与 episode 状态隔离、fp8/INT8 量化、torch.compile/CUDA Graph、obs 预取与 chunk 预热、`image_resize` 压带宽（4×(240,320) 使每步载荷降约 4×）、断线重连 + 健康探针。
- **可行性**：高（纯工程）。
- **资源**：1 台多卡推理机（≥2×A100 80G，视 N 定）；1–2 人周。
- **步骤**：①本地 run_client 压测 p50/p99；②故障注入（并发/断网/显存压力）；③元参数联合网格扫描（chunk_size × resize × 历史长度）；④冻结服务配置版本，任何改动过 PR4 门禁。
- **风险**：量化精度损失（缓解：量化前后输出差值回归测试）；并发竞态（缓解：端口独立队列）。

### I7 世界模型测试时前瞻 ★★（缓）
- **动机**：官方 WMA-0 定位即「策略增强：预测未来交互优化决策」（F6）；在抓取前/插入前等高险节点做 O(1–2) 次小规模 rollout 择优。
- **差异**：纯前馈策略 → 关键节点 test-time 搜索。
- **可行性/资源/风险**：中；需世界模型权重 + 1 张独立 GPU（不占控制路径）；风险是延迟预算爆炸与世界模型在泛化轴上的预测偏差（只在低时敏节点用）。
- **决定**：第 2 轮视基线延迟余量决定保留或裁撤（清单修剪项）。

### I8 评测运营闭环（先手迭代） ★★★★
- **动机**：榜单未上线 + 单任务通道免费（F7/F8），先手高频迭代 = 排名复利（P7）。
- **做法**：周节奏「诊断（单任务通道 + runs 评测视频失败分析）→ 修复（I1–I6）→ 提交」；每次提交前过 PR4 门禁；建立失败视频库与错误 taxonomy（分轴统计失败原因），反哺 I1/I2 的优先级。
- **风险**：预约排期不可控（缓解：多时段预约 + 离线验证兜底）。

```python
class FiveAxisAugmentor:
    # axis -> editor；保证「视觉变、动作语义不变」为唯一不变量
    def augment_episode(self, ep):
        out = []
        for axis in sample_axes(p={"background": .4, "distractor": .4,
                                   "appearance": .2, "position": .2}):
            ep2 = copy(ep)
            if axis == "background":            # 仅图像域，动作不动
                ep2 = replace_background(ep2, inpaint=True, qa_gate=True)
            elif axis == "distractor":          # 注入非接触区域杂物
                ep2 = inject_clutter(ep2, outside_gripper_workspace=True)
            elif axis == "appearance":          # 同类不同外观（未见物品轴）
                ep2 = swap_object_appearance(ep2, same_category=True)
            elif axis == "position":            # 技能段重组 + ee 刚体变换
                segs = segment_skills(ep2)      # approach / transport / place
                T = sample_rigid_offset(margin=EPS_SUPPORT_RADIUS)
                ep2 = reassemble(segs, transform_ee(segs, T))
            if self.qa_pass(ep2):               # 增广 QA 门禁，伪影即弃
                out.append(ep2)
        return out
```

### 1.2 策略服务外层状态机（I3+I4+I5 组合，单服务内）

```python
class GuardedPolicy:  # 唯一参赛实体：一个 PolicyService
    def __init__(self):
        self.vla   = load_wla_base_finetuned()      # 通才 chunk 策略（I2 产物）
        self.hand  = HandDetector()                  # 零训练人手检测
        self.servo = KeypointServo(task_family="contact_rich")  # I3（边界确认后）
        self.prog  = ProgressHead()                  # I5 步骤分导向
        self.state = FSM(default="EXECUTE")

    def get_action(self, obs):
        imgs = stack(obs)                            # obs_delta_indices 历史
        if self.hand.detect(imgs[-1]) or self.interrupted(imgs):
            self.state.enter("YIELD")                # PR3：让位→重估→续做
        if self.state == "YIELD":
            if self.hand.clear(imgs[-1]) and self.rescan(imgs):
                self.state.enter("EXECUTE"); self.chunk_len = 4   # 短 chunk
            else:
                return safe_hold()                   # 界内平滑停持
        plan = self.vla.propose_chunk(obs, k=self.chunk_len)       # chunk_len 自适应
        if self.stuck(self.prog(imgs)):              # 进度导数 < ε 持续 k 步
            plan = recovery_primitive(plan, k_max=2)               # I5 回退原语
        if self.near_contact(plan) and self.servo.confident(imgs):
            plan = self.servo.correct_tail(plan, imgs)             # I3 只接管末端
        return clip_smooth(plan)                     # 动作健康度：界内+平滑
```
