# 想法区 · 第 8 轮：让「未来」成为一个偏序，用闭包算分支上界

**灵感词**：计算复杂度 / upper bound / 迭代
**起点**：v1.7「X-DUB/PACE-Q*」。38 例上 187 节点 / 0.041 s / 51 表；deep suite 3,216 → 1,792；hard3#5 216 → 130；两个 deep 实例被 HPACK 在根部一张证书闭掉。v1.7 的收官风险写得很直白：**ODOM 要有同 `(p,E,Succ_R)` 的就绪任务，HPACK 要有强制重叠的整性矛盾；两者都不满足时，Q 退回 v1.6 的 273 节点，并多付装箱开销。**

第 8 轮我不想再加一条「只在 hard3#5 上好看」的不等式。灵感词里有「upper bound」和「计算复杂度」，于是一个更基本的问题浮出来：

> **搜索的分支因子到底被什么上界控制？这个上界能不能在多项式时间里算出来，并且真的达到？**

v1.6 的答案是「`|READY|`」，v1.7 的 ODOM 把它压到「交换类数」。但 ODOM 的商是**语法**的：它只认 `Succ_R(i)=Succ_R(j)` 这种相等。两个就绪任务，一个的未来是另一个的**子集**时，ODOM 看不见。而这正是「先做谁」最朴素的一类冗余：**别先做死路**。

## 一、直觉：如果 i 的全部未来都包含在 j 里，就先做 j

在状态 `σ=(R,A,est)`，任务 `i` 对未来的全部直接影响是：占一台机器 `p_i` 个时间单位，并把 `Succ_R(i)` 的最早开始抬到 `C_i`。所以，如果

```text
p_i = p_j,  E_i = E_j,  且 i 在残余图里的所有后裔都也是 j 的后裔,
est_j ≤ est_i,
```

那么把「i 先、j 后」的两个时间槽互换，让 **j 去 i 的较早槽、i 去 j 的较晚槽**：

- 共同的后继看到的是 `{C_i, C_j}` 这个**多重集**，交换后不变；
- 只在 j 的后裔里、不在 i 的后裔里的任务，看到 j 更早完成，只会更松；
- 只在 i 的后裔里的任务——不存在，因为 i 的未来被 j 包含；
- i 被移到更晚的槽，释放时间只会更松；j 被移到 `s_i`，需要 `est_j ≤ s_i`，而 `s_i ≥ est_i ≥ est_j`。

所以可行性和 makespan 都不变，而 j 提前了。**每个「未来被包含」的对，都可以把包含者提前。** 这是一个偏序；搜索只需要在每个状态分支它的**极大元**。一个汇点（没有后裔）是极端情形：它的未来是空集，被任何同时长、同资格、不更晚的任务包含——**汇点永远不必先做**。

直观一句话：**一个任务的「未来」是它所有后裔的集合；未来越大越该先做，未来是别人子集的可以缓一缓。**

## 二、形式化：残余后裔集与支配预序

在 σ 下定义残余后裔集

```text
D_σ(i) = { t ∈ R : 残余图里存在 i → … → t 的路径 }        （严格后裔，不含 i）
```

定义预序

```text
i ≼_σ j  ⟺  p_i=p_j ∧ E_i=E_j ∧ D_σ(i) ⊆ D_σ(j) ∧ est_j ≤ est_i .
```

等号情形用 `(D_σ, est, 索引)` 破平。**交换引理**（下一节的定理 1）说：若 `i ≼ j` 且 i 在 j 之前开始，则交换两个槽后仍可行，且 j 不晚于 i。于是存在一个可行排程，它**开始最早的任务是 ≼-极大元**（否则把支配它的极大元换到最前，仍可行）；对子状态递归，每一步都只需试极大元。所以

```text
分支集 K(σ) = Max_≼(READY(R))，  |K(σ)| = c(σ) ≤ |READY(R)| = d.
```

这就是本轮要找的 **upper bound**：分支因子的上界不是 `d`，是 `c(σ)`。而 `c(σ)` 可以在 `O(d²)` 次位集包含测试里算出来，不需要枚举线性扩展。

## 三、「迭代」的两层含义

第一层是**闭包迭代**。`D_σ(i)` 不是输入，而是后继关系的传递闭包：

```text
D^{(0)}_i = Succ_R(i)
D^{(k+1)}_i = Succ_R(i) ∪ ⋃_{t ∈ Succ_R(i)} D^{(k)}_t
```

不动点就是 `D_σ(i)`。实现里 `po.make_inst` 已经按逆拓扑序一次算出静态 `desc`；在状态里取 `desc(i) ∩ R` 就是残余后裔集（未调度任务的后裔不可能已被调度，所以这个交是精确的，见产物区引理 1）。

第二层是**每节点的 skyline 迭代**。把 ready 按 `(est, 索引)` 升序扫一遍，维护一个 `keep` 列表：

1. 新任务 i：若存在 `j ∈ keep` 满足 `p,E` 相同且 `D_i ⊆ D_j`，则 i 被支配，丢弃；
2. 否则，i 可能反过来支配 `keep` 里某些 j——但只能在 `est_j = est_i` 且 `D_j ⊊ D_i` 时（因为 `est_j ≤ est_i` 是支配者必须满足的）。把这些 j **驱逐**，再把 i 加入。

第 2 步的「驱逐」不是可选的。我第一版只检查「i 是否被更早的 keep 支配」，不驱逐；在 deep#1 上得到 177 节点，而正确版本是 116。原因：同一 `est` 下，索引大的任务可能有**严格更大**的未来集，它应该反过来支配索引小、未来小的任务。只向前看的 skyline 算的是「前缀极大元」，不是「极大元」；它仍然是 sound 的（少删几个），但会漏掉一大截商。这个 bug 是被定理 2 的「keep = 极大元」不变量抓出来的，不是被对拍抓出来的——对拍只会告诉你两边都返回 NO，不会告诉你少商了 61 个节点。

## 四、复杂度的诚实版本

- **每节点**：排序 `O(d log d)`，包含测试 `O(d²)` 次；位集是 n 位，按机器字算是 `O(d²·n/64)`。在 n≤16、m=3 的规模上，这比 v1.6 已有的 `potential`（约 `O(n³)` 个窗口-任务操作）便宜一个量级。
- **总节点**：`N_DCD ≤ N_ODOM`。因为 ODOM 的每个交换类代表要么被 DCD 保留，要么被一个未来更大的任务支配掉；DCD 的分支集是 ODOM 分支集的**子集**，所以（未加 memo 的）搜索树是 ODOM 树的子树。节点数 ≤ 正规形线性扩展数。
- **最坏情况**：仍然是线性扩展计数，指数级。构造一个「每个 ready 任务都有私有后裔、未来两两不可比」的实例，`c=d`，DCD 一次都不触发。**本轮没有改进最坏情况复杂度，只改进了一个数据相关的商。**
- **最好情况**：若每个状态的 ready 集只有一个极大元，树退化成一条路径（`n+1` 个节点）。例如所有任务等时长、无优先约束、未来全为空：DCD 每个状态只留一个代表。

所以「计算复杂度」在本轮的正确说法是：**我们算出了分支因子的一个可计算上界 `c(σ)`，并证明它不超过 ODOM 的类数；但没有改变指数下界。**

## 五、试过但没用的、以及不敢用的

### 5.1 能量尾部：sound，但零效果

一个很自然的上界强化是给每个任务一个「能量尾部」：

```text
q_i^E = max( q_i^path,  ceil( Σ_{t ∈ D_σ(i)} p_t / m ) )
```

它是对的（i 完成后，所有后裔都要在 m 台机器上做），但 hard3#5 和 deep 8 例上**节点数一个都没变**（115/1042 逐字不变）。原因是这些实例的 `q^path` 已经支配了能量项；窗口能量也早就覆盖了同一信息。这是一个「看起来该有用、实际被已有层吸收」的负结果。

### 5.2 est 的不等号方向：证明过不去，就不发货

我最初把条件写成 `est_j ≥ est_i`（「j 虽然更晚可用，但未来更大，所以先做 j」），在 hard3#5 上也能降到 115，看起来很美。但交换要求 j 坐进 i 的**较早槽** `s_i`，必须 `est_j ≤ s_i`；静态可用的充分条件只能是 `est_j ≤ est_i`。反方向没有交换证明。

我跑了 60,000 个随机小实例找反例，**一个都没找到**。这恰恰是危险的地方：如果只看对拍，我会把一条没有证明的规则发出去。最后我把它扔了——不是因为它被证伪，而是因为它没有被证明。研究循环里，「没找到反例」不是「定理」。

### 5.3 直接后继包含：sound，但只是闭包的 depth-1 版本

把 `D_σ` 换成 `Succ_R`，条件 `Succ_i ⊆ Succ_j` 也是 sound 的（它是 `D_i ⊆ D_j` 的特例）。它比闭包弱：deep 上 HPACK 一起用时 1,160 vs 1,042。它保留在实现里作为 `dcd_direct` 消融，说明「迭代到不动点」本身贡献了约 1.11×。

## 七、一句话最大风险

**DCD 只在「同时就绪、等时长、等资格、未来集真包含、且包含者不更晚」时生效；若真实负载的 ready 任务未来互不包含（连续加工时间、独立并行分支、或异资格），分支因子回到 d，deep 上相对 v1.6 的 3.09× 会退化为 1×，只剩 O(d²) 的空转检查。**

# 产物区 · v1.8：X-DUB/PACE-D*

> PACE-D = PACE with **D**escendant-closure dominance。
> 在 v1.7 的 `ODOM`（交换类）与 `HPACK`（强制重叠装箱）之上，本轮只加一层：

1. **`DCD`（tier 0.3）**：定义残余后裔集 `D_σ(i)` 与支配预序
   ```text
   i ≼_σ j  ⟺  p_i=p_j ∧ E_i=E_j ∧ D_σ(i) ⊆ D_σ(j) ∧ est_j ≤ est_i .
   ```

## 2. 形式定义

### 2.1 残余后裔集

**定义 1（残余后裔集）**。在状态 `σ=(R,A,est)`，

```text
D_σ(i) = { t ∈ R : 残余图 G[R] 中存在有向路径 i → … → t } .
```

**引理 1（静态交的精确性）**。若 `i` 是 ready 的（`i∈READY(R)`），则

```text
D_σ(i) = desc(i) ∩ R ,
```

其中 `desc(i)` 是完整 DAG 里 i 的严格后裔集。

**证明**。

- `⊆`：残余路径也是完整图里的路径，且终点在 R 中。
- `⊇`：取 `t ∈ desc(i) ∩ R`，完整图里有一条路径 `i=v0→v1→…→vk=t`。若某个 `v_l ∉ R`，则 `v_l` 已被调度；但 `v_l` 是 i 的后裔，调度 `v_l` 时 i 必须已调度（DEC 的拓扑不变式：调度一个任务时其所有前驱已调度），与 i 未调度矛盾。故整条路径都在 R 中，`t ∈ D_σ(i)`。∎

这个引理让每节点的 `D_σ(i)` 退化成一次位与：`inst['desc'][i] & rem`，不需要在残余图上重新做闭包。

### 2.2 支配预序

**定义 2（DCD 预序）**。在 σ 上，

```text
i ≼_σ j  ⟺  p_i=p_j ∧ E_i=E_j ∧ D_σ(i) ⊆ D_σ(j) ∧ est_j ≤ est_i .
```

`≼_σ` 是预序：自反、传递（`⊆` 与 `≤` 各自传递）。它一般不是反对称的：若 `D_i=D_j`、`est_i=est_j`、`p,E` 相同，则 `i≼j` 且 `j≼i`。为得到严格偏序，定义

```text
i ≺_σ j  ⟺  i ≼_σ j  ∧  ( D_σ(i) ≠ D_σ(j)  ∨  est_i ≠ est_j  ∨  i < j ) .
```

`≺_σ` 是严格偏序（非自反、传递），两个等价任务（`D,est,p,E` 全同）只保留索引小者。

**注（与 ODOM 的关系）**。v1.7 的 ODOM 要求 `(p,E,Succ_R)` 全等；由引理 1，`Succ_R` 全等 ⇒ `D_σ` 全等，所以 ODOM 是 `≼_σ` 的一个特例（相等情形）。DCD 严格更粗：它允许 `D_i ⊊ D_j`。

### 2.3 正规形

**定义 3（DCD 正规形）**。从 σ 出发的排程是 σ-正规的，若它**开始最早**的任务（并列取索引小）是 `≼_σ`-极大元，且删除这个任务后的残余排程在相应子状态下正规。

这是递归定义，不是「对所有 `i≺j` 排序」的全局定义。全局版本在非就绪任务上会碰到「j 的未调度前驱可能晚于 s_i」的问题；递归版本只要求每一步的第一个任务极大，正好是完备性需要的。

### 2.4 分支集

**定义 4（DCD 分支集）**。

```text
K_DCD(σ) = Max_≼_σ(READY(R)) .
```

PACE-D 在每个状态只对 `K_DCD(σ)` 里的任务生成子节点。

## 3. 算法

### 3.1 每节点的 skyline

```text
DCD-BRANCH(σ):
    ready ← READY(R)
    order ← sort ready by (est_i, i)          # 非降 est；等 est 按索引
    keep  ← []
    for i in order:
        D_i ← desc(i) ∩ R                     # 引理 1
        dominated ← False
        for j in keep:
            if p_j ≠ p_i or E_j ≠ E_i: continue
            if D_i ⊆ D_j:                     # j 不晚于 i，且未来更大
                dominated ← True; break
        if dominated:
            drop i; continue
        # 同 est 的驱逐：i 是 j 的严格超集，i 反过来支配 j
        keep ← [ j ∈ keep : ¬( p_j=p_i ∧ E_j=E_i ∧ est_j=est_i ∧ D_j ⊊ D_i ) ]
        keep.append(i)
    return keep
```

**循环不变式**。处理完 `order` 的前缀 P 后，`keep = Max_≼(P)`。

**证明**。

- 基础：空集。
- 归纳：新任务 i 到来。
  - 若存在 `j∈keep` 满足 `p,E` 相同、`D_i⊆D_j`：由排序 `est_j≤est_i`，故 `j≼i`，i 不是极大元，丢弃。
  - 否则 i 不被 P 中任何任务支配（任何支配者 j 必有 `D_i⊆D_j` 且 `est_j≤est_i`，且 j 已在 P 中；若 j 已被从前缀 keep 驱逐，则它有被 keep 中某个 k 支配，传递得 k 也支配 i，矛盾）。
  - i 可能支配 P 中的 j：需要 `D_j⊆D_i`、`p,E` 相同、`est_i≤est_j`。排序给出 `est_i≥est_j`，故只能 `est_i=est_j`。若 `D_j=D_i`，等 est 下 j 的索引更小，按 `≺` 的破平 j 先于 i，i 不支配 j，且 3.1 的第一段会把 i 判为被 j 支配（因为 `D_i⊆D_j`），不会走到这里。故只剩 `D_j⊊D_i`，这些 j 必须驱逐。
- 所以 keep 恰好是 `Max_≼(P∪{i})`。∎

**复杂度**。排序 `O(d log d)`；主循环每个 i 与至多 c 个 keep 比较，驱逐再扫一遍 c，共 `O(d·c)` 次位集包含测试。位集 n 位，按 64 位字算是 `O(d²·n/64)` 字操作；Python 大整数把它压成 `O(d²)` 次 C 层大整数与/非。n≤16 时 d≤16，最坏 256 次测试，远小于 `potential` 的 `O(n³)` 窗口-任务操作。

### 3.2 接进 PACE-Q 的搜索

```text
PACE-D(σ,h):
  1  if R=∅: return YES([])
  2  if DEAD(σ): return NO
  3  σ←NORM(σ); A*←CANON(A); estt←est|R
  4  exact memo / F_sub / INT                            # v1.7，不变
  5  window 层: energy / clique / subset / HPACK          # v1.7，不变
  6  MINT / PACK-SET / SOP                                # v1.7，不变
  7  if ¬PACK(σ,h): F_pack.insert; return NO(PACK)        # v1.7，不变
  8  K ← DCD-BRANCH(σ)                                   # 本轮唯一改动
  9  for i in K:
         for k in machines(i):
             t ← max(A_k,est_i)
             if t+p_i+q_i(R\{i}) > h: continue
             r ← PACE-D(child(i,k,t))
             if r=YES: return YES([(i,k,t)]+r)
 10  F_sub.insert(estt,A*); return NO(RESOLVE)
```

与 v1.7 的差异只有第 8–9 步：v1.7 遍历交换类代表，PACE-D 遍历 `Max_≼`。第 9 步里的 `machines(i)` 仍是 v1.6 的 `DISPATCH(i,σ)`（全资格）或 `E_i`（异资格），不变。

### 3.3 实现细节

- `desc(i)` 在 `po.make_inst` 里按逆拓扑序一次算出；状态里 `desc(i) & rem` 是引理 1 的精确残余后裔集。
- `dcd_branch_set(ready, p, elig, fut, est)` 返回 `(keep, drop, eq_drop)`；`eq_drop` 只用于统计「等未来集」的丢弃数。
- `dcd_direct=True` 把 `fut` 换成 `Succ_R`，只用于消融；默认 `False`。
- `est` 是经过 `NORM` 的；`NORM` 只抬高 est，不改变排序，所以引理 1 与交换引理在 NORM 后仍成立。
- 不新增记忆表；DCD 是无状态的每节点过滤。

## 4. 定理与证明

### 4.1 交换引理

**定理 1（descendant exchange）**。设 `σ=(R,A,est)`，`i,j∈READY(R)` 满足

```text
p_i=p_j=p,  E_i=E_j,  D_σ(i) ⊆ D_σ(j),  est_j ≤ est_i ,
```

且存在从 σ 出发的可行排程 S，S 中 `s_i ≤ s_j`。把 i、j 的**机器与开始时刻整体互换**（i 去 `s_j`、机器 `k_j`；j 去 `s_i`、机器 `k_i`），其余任务不动，得到 S'。则 S' 可行，makespan 不变，且 j 不晚于 i。

**证明**。记 `C_i=s_i+p`、`C_j=s_j+p`。

- **资格**：`E_i=E_j`，所以 j 能上 `k_i`，i 能上 `k_j`。
- **释放**：
  - j 去 `s_i`：`s_i ≥ est_i ≥ est_j`（用 `est_j≤est_i` 与 `s_i≥est_i`）。
  - i 去 `s_j`：`s_j ≥ s_i ≥ est_i`。
- **机器**：两个槽长度都是 p；交换后每台机器上的占用区间集合不变（只是 i/j 的身份互换）。
- **优先**：只有 `C_i,C_j` 改变：`C_i'=C_j`，`C_j'=C_i`。
  - 对 `t∈Succ_R(i)`：由 `D_i⊆D_j` 得 `t∈D_j`，即 S 中 t 在 j 之后（沿路径传递），故 `s_t ≥ C_j = C_i'`；又 t 是 i 的后继，`s_t ≥ C_i = C_j'`。所以 `s_t ≥ max(C_i',C_j')=C_j`，约束满足。
  - 对 `t∈Succ_R(j)\Succ_R(i)`：`s_t ≥ C_j ≥ C_i = C_j'`，j 更早完成，约束更松。
  - 其余任务的前驱完成时刻不变。
- **期限**：`C_i'=C_j≤h`，`C_j'=C_i≤h`。
- **makespan**：完成时刻的多重集只交换了 `C_i` 与 `C_j`，其余不变，故 `max` 不变。

所以 S' 可行，且 j 在 `s_i≤s_j`。∎

**注（为什么必须是 `est_j ≤ est_i`）**。交换要求 j 坐进 i 的较早槽 `s_i`，而 `s_i` 的静态下界只有 `est_i`；所以充分条件是 `est_j ≤ est_i`。反过来写 `est_j ≥ est_i` 在数值上也会剪，但这一步过不去。6.2 详述。

### 4.2 正规形与完备性

**定理 2（DCD 完备性）**。若存在从 σ 出发的可行排程，则存在 σ-正规形可行排程；并且 PACE-D 的受限分支（只试 `Max_≼`）是完备的。

**证明**。对 `|R|` 归纳。取任一可行 S，令 i 为 S 中**开始最早**的任务（并列取索引小）。

- **i 必 ready**：若 i 有前驱 p∈R，则 p 在 i 之前完成，故 p 的开始早于 i，与 i 最早矛盾。所以 `i∈READY(R)`。
- **若 `i∈K_DCD(σ)`**：PACE-D 分支 i。子状态把 i 放在 `t=max(A_k,est_i)≤s_i`；子状态的 `A`、`est` 都不晚于 S 去掉 i 后的对应值，所以残余 S 仍可行。由归纳，子树返回可行排程。
- **若 `i∉K_DCD(σ)`**：由 `≼` 的有限性，存在极大元 `j∈K_DCD(σ)` 使 `j≺i`（沿支配链走到底）。i、j 都 ready，且 `s_i≤s_j`；由定理 1 交换两个槽，得到可行 S'，j 在 `s_i` 开始。PACE-D 分支 j。子状态把 j 放在 `t=max(A_k,est_j)≤s_i`；同样，子状态的 `A`、`est` 不晚于 S' 去掉 j 后的值，残余 S' 仍可行。由归纳，子树返回可行排程。∎

**注（为什么不需要全局正规形）**。如果试图把所有 `i≺j` 的对都排成 j 先于 i，交换引理会作用到**非就绪**的 j：它的未调度前驱在 S 中可能晚于 `s_i` 完成，j 移到 `s_i` 会违反优先约束。递归定义只交换「当前状态的两个 ready 任务」，避开了这个坑。这是本轮在证明上比 v1.7 更小心的地方。

**注（派工序 ≠ 开始序）**。定理 2 选的是开始最早的 i；PACE-D 的派工序列可以把它排在任意位置，但子状态把它放在 `t=max(A_k,est_i)≤s_i`，因此不会比 S 更晚。如果 DFS 先派了别的任务，i 仍可能落在同一台机器的较早空闲槽；完备性只要求存在一条派工序重现正规形（按开始时刻序派工即可）。

**注（公共期限）**。交换只用了 `C_i,C_j≤h`，没有用 `d_i=h−q_i` 的个体期限；所以只要所有任务共享 h，证明成立。若任务有各自期限，交换需要额外条件 `C_i'≤d_i`、`C_j'≤d_j`（或至少 `s_i+p≤d_j`、`s_j+p≤d_i`），与 v1.7 的注意事项相同。

### 4.3 分支上界与子树

**定理 3（fan monotonicity / subtree）**。对任意状态 σ，

```text
K_DCD(σ) ⊆ K_ODOM(σ) ,   从而 c_DCD(σ) ≤ c_ODOM(σ) ≤ d .
```

并且（不加 memo/front 的）DCD 搜索树是 ODOM 搜索树的子树，节点数不超过 ODOM 的节点数。

**证明**。取 `i∈K_DCD(σ)`。若 `i∉K_ODOM(σ)`，则存在 j 与 i 同 `(p,E,Succ_R)` 类且 `(est_j,j)<(est_i,i)`。同 `Succ_R` ⇒ 同 `D_σ`（按定义展开：相同的后继集合给出相同的闭包），且 `p,E` 相同。若 `est_j<est_i`，则 `j≺i`，i 不是极大元，矛盾；若 `est_j=est_i` 且 `j<i`，则 `j≺i`（破平），同样矛盾。故 `i∈K_ODOM(σ)`。

子树：每个状态的 DCD 子节点集合是 ODOM 子节点集合的子集；对深度归纳即得。∎

**推论（节点上界）**。设 `L_DCD(σ)` 为 σ-正规形线性扩展数，则

```text
N_DCD(σ) ≤ 1 + n · L_DCD(σ) ,     L_DCD(σ) ≤ L_ODOM(σ) ≤ n! .
```

最坏情况 `L_DCD=n!`（未来两两不可比、est 又允许全部并列），最好情况 `L_DCD=1`（每个状态只有一个极大元，树退化成一条路径）。

### 4.4 复杂度

设 `d=|READY(R)|`，`c=|K_DCD|`，位集 n 位、字长 ω=64。

```text
DCD 每节点:
    排序            O(d log d)
    包含测试        O(d·c) 次，每次 O(n/ω) 字操作
    最坏            O(d²·n/ω + d log d)
    存储            O(d)

主搜索:
    N(σ) = 1 + Σ_{i∈K_DCD(σ)} N(σ_i)
    N ≤ 正规形前缀数 ≤ n · L_DCD
    最坏仍为指数；本轮不改变最坏复杂度
```

**成本位置**。`potential` 每节点枚举 `O(n²)` 个窗口、每窗口 `O(n)`，约 `O(n³)`；DCD 的 `O(d²)` 位集测试比它低一个量级。deep suite 上时间从 0.2436 s（v1.7）降到 0.1769 s（v1.8），节点减少抵消了 DCD 的检查。

**最好/最坏的语言**。最好情形是「每个 ready 集只有一个极大元」：例如所有任务等时长、无优先约束、后裔全空——DCD 每状态只留一个代表，树是一条路径。最坏情形是「每个 ready 任务都有私有后裔、未来两两不可比」：`c=d`，DCD 一次都不触发，退回 v1.6 的分支因子。**所以 DCD 是一个数据相关的商，不是渐进改进。**

| 返回排程独立验证（任务一次、优先、机器不重叠、资格、h） | 随机对拍所有 YES + 38/deep 的 46 个 h=OPT YES | 0 违规 |
| `dcd_branch_set` vs 暴力极大元 | 20,000 组随机 + 驱逐反例 | **20,000/20,000 通过** |
| v1.7 资产（ODOM/HPACK/MINT/PACK-SET/SOP/INT） | — | 未改动；关 DCD、保留 ODOM 与 HPACK 时逐字复现 187 |

**“0 不一致”的含义**：base 与 DCD 在同一个引擎、同一个 h 上返回同一个布尔值；YES 时两边都独立验证排程。穷举覆盖了 n≤5 的所有 DAG 与所有 h，这是比随机对拍更强的证据，但仍不是形式化验证。

## 6. 负结果与实现陷阱

### 6.1 能量尾部：sound，但零效果

一个自然的上界强化是给每个任务一个能量尾部：

```text
q_i^E = max( q_i^path,  ceil( Σ_{t∈D_σ(i)} p_t / m ) ) .
```

它是对的：i 完成后，所有后裔都要在 m 台机器上做，至少需要 `ceil(Σp/m)` 的时间。但 hard3#5 的 115 和 deep 的 1,042 **一个节点都没变**。原因是 `q^path` 已经支配了能量项（hard3#5 的 CP=37 > 30），窗口能量也早已覆盖同一信息。这是一个「看起来该有用、实际被已有层吸收」的负结果；不建议再加。

### 6.2 est 的不等号方向：没有证明就不发货

我最初写的条件是 `est_j ≥ est_i`（「j 更晚可用但未来更大，所以先做 j」）。它在 hard3#5 上也能到 115，看起来一样好。但交换要求 j 坐进 i 的较早槽 `s_i`，必须 `est_j ≤ s_i`；静态充分条件只能是 `est_j ≤ est_i`。反方向没有交换证明。

我跑了 60,000 个随机小实例找反例，**一个都没找到**。这恰恰是危险的地方：如果只看对拍，我会把一条没有证明的规则发出去。最后我把它扔了——不是因为它被证伪，而是因为它没有被证明。**没找到反例 ≠ 定理**；这是本轮方法论上最重要的一条。

### 6.3 skyline 的驱逐步：sound 但会少商

第一版 skyline 只检查「i 是否被更早的 keep 支配」，不驱逐。它在 deep#1 上给 177 节点，正确版本 116。原因：同 `est` 下，索引大的任务可能有严格更大的未来集，它应该反过来支配索引小、未来小的任务。只向前看的 skyline 算的是「前缀极大元」，不是「极大元」。

它仍然是 **sound** 的：每个被丢弃的任务都被一个保留任务真正支配，所以不会假 NO；只是少商了 61 个节点。这是「正确性」与「强度」分离的典型：对拍永远发现不了它。

### 6.4 直接后继包含：sound，但只是 depth-1

`Succ_i ⊆ Succ_j` 也是 sound 的（它是 `D_i ⊆ D_j` 的特例），但 deep 上 1,160 vs 1,042。保留为 `dcd_direct` 消融，说明闭包迭代本身贡献 1.113×。

### 6.5 hard3#5 根仍未闭

115 节点不是根证书，是搜索树。根的总容量 slack=24（最小窗口 slack=1 但可装），单窗口 HPACK 没有整性矛盾；DCD 只剪顺序冗余。要根闭，需要「固定位置强制段 + 残余能量」或「跨窗口联合装箱」的更强割——本轮没有实现。这是 v1.9 最自然的入口。

## 8. 已知风险

1. **收益高度数据相关**：DCD 要求同时就绪、`p` 与 `E` 完全相等、未来集嵌套、且包含者 `est` 不更晚。四项缺一，分支因子回到 `d`。连续加工时间或独立并行分支上，DCD 可能一次都不触发。
2. **最坏复杂度没变**：仍是线性扩展计数，指数级。deep 的 3.086× 是按 base≥200 挑过的 8 例；held-out 的 1.179× 才是更诚实的期望。
3. **38 例的收益仍集中在 hard3#5**：216→115；其余 37 例逐字不变（large_het#1 仍是 21）。这不是普遍加速。
4. **hard3#5 没有根闭**：115 是搜索树，不是证书；根因是优先约束与机器分配，不是容量整性。
5. **`p,E` 必须完全相等**：`E_i ⊆ E_j` 或 `p_i ≤ p_j` 都没有交换证明；异资格实例上 DCD 只在资格集**完全相同**的任务之间比较，收益更窄。
6. **公共期限 h**：证明只用 `C_i,C_j≤h`；若任务有个体期限，交换需要额外条件，和 v1.7 的 ODOM 一样要重证。
7. **est 方向不可反**：`est_j ≤ est_i` 是交换的硬条件；反方向没有证明，60k 随机无反例也不够。
8. **skyline 的驱逐步是强度关键**：不驱逐仍然 sound，但会少商（deep#1 177 vs 116）；实现时必须按「极大元」而不是「前缀极大元」写。
9. **最坏情况无剪枝**：私有未来两两不可比时 `c=d`，DCD 纯开销 `O(d²)`；在浅树/易实例上这 6.9% 的时间是实打实的。
10. **`D_σ(i)=desc(i)∩R` 依赖未调度任务的后裔不可被调度**：这是 DEC 的拓扑不变式；若移植到允许「部分调度/抢占」的模型，引理 1 不成立。
11. **DCD 与 memo/front 的交互只做了对拍**：DCD 改变分支集后，`F_sub`/`F_pack` 的命中顺序会变；理论上 sound，但没有单独的归纳证明「DCD 树是 ODOM 树的子树」在 memo/front 下仍逐节点成立（经验上节点数不增）。
12. **实验规模**：n≤16，m=3，deep 只有 8 例；held-out 50 例但都是全资格。n≥22、m≥4、PSPLIB 未测。
13. **时间常数是 Python 的**：38 例 0.0404 vs 0.0412 在噪声内；节点数与表数是确定性的，时间比不是。
14. **没有形式化验证**：16,000 随机 + 251,904 穷举 + 20,000 skyline 单测是很强的证据，但不是 Coq/Lean；定理 1–3、引理 1 与 skyline 不变量是纸面证明。
15. **2/8 的根闭是 HPACK 的旧资产**：不能算作 DCD 的贡献；DCD 在根上只处理顺序，不产生割证书。
16. **`dcd_direct` 只是消融**：它 sound 但弱，默认关闭；不要把它当成「轻量版 DCD」部署到需要强剪枝的深树。

---

## 9. 一句话最大风险

**DCD 只在「同时就绪、等时长、等资格、未来集真包含、且包含者不更晚」时生效；若真实负载的 ready 任务未来互不包含（连续 p、独立并行分支、异资格），分支因子回到 d，deep 上相对 v1.6 的 3.09× 会退化为 1×，只剩 O(d²) 的空转检查。**
