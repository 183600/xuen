# 想法区 · 第 1 轮：一个节点就是一个词——三次否证之后，剪枝规则的价值由机器常数决定

**灵感词**：图灵机 / quantum algorithm / adaptivity
**起点**：v2.5「X-DUB/PACE-ΠA-BBX」。它在 50 个 held-out 上拿到 1.90×，节点 80,463→57,236（−28.9%），每节点 6.31→4.30 µs（−32%）。它的收官风险是一句话：

> 这一轮的 1.9× 全部来自「同一棵指数搜索树被剪掉 28.9%、每个节点便宜 1.50×」这两个常数，而不是任何新的可证明下界；一旦分布让 RSI 不触发（或 n>16 出门），剩下的就只有打包的 1.50×。

我同意这句话的描述，但不同意它的隐含结论——「下一个因子还得靠一个新的剪枝规则」。这一轮我先把三个自然的下一步都**测量一遍**，结果是两个死、一个活；而活下来的那个不是新剪枝，是**机器模型**。更意外的是：一旦把节点成本压到 2.2 µs，v2.5 明确判死的 forcing 就翻盘了。**同一条剪枝规则的值不是规则的性质，是 (规则, 机器常数) 的性质。**

---

## 一、先问一个更基本的问题：这棵树为什么不能更小

v2.5 的 OS 在 NO 上是一个带精确 memo 的 DFS。状态是 `(mask, CP, RP)`，memo 命中率 52%（57,236 次调用 / 27,277 个展开状态）。v2.5 的序不变性定理说：NO + 精确 memo + 无 dominance 时，调用数 = 1 + 可达状态图的边数，展开数 = 节点数，**与兄弟顺序无关**。

这句话比它看起来更强。它意味着：

```
在这棵树上，任何「换顺序 / 换遍历 / 换启发式」的改动都是零收益。
唯一能改变成本的，是改变状态集合本身（商掉状态，或剪掉状态），
或者改变「一个状态要花多少机器周期」。
```

于是本轮只有三个候选方向：

1. **商**：`(mask, CP, RP)` 还能不能再合并？（图灵机的配置图能不能更小？）
2. **剪**：有没有比 RSI 更强的、便宜的、可靠的局部必要条件？（能量界 / Hall 割）
3. **机器**：一个节点能不能是常数条**字**操作？（图灵机的字长）

我先做了 1 和 2，都是否证；然后 3 成了，并且把 2 里被否掉的一条规则救了回来。

---

## 二、实验一：状态图不可再商

自然的猜想是：`CP` 里有很多位对**剩余任务**毫无用处。一个剩余任务 i 只可能在 `[r_i, d_i)` 里执行，所以在这之外的容量位永远用不到。于是可以做一个**精确商**：

```text
hull(σ) = [ min_{i∈R} r_i , max_{i∈R} d_i )
key     = (mask, CP & fieldmask(hull), RP)
```

两个只差 hull 之外容量的状态，未来完全一样——这是可证明的，不是启发式。我把它接进内核，跑 50 个 held-out：

| 内核 | 节点 | memo key |
|---|---:|---:|
| v2.5 精确 key `(mask,CP,RP)` | 57,236 | 27,277 |
| hull 商 | 57,232 | 27,270 |

**只合并了 4 个节点。** 这等于说：在这批数据上，`(mask, RP)` 几乎已经决定了 `CP` 在有用区间上的取值；那 52% 的 memo 命中不是冗余，是真实的 DAG 汇合。想靠「更聪明的 key」再省一半节点，没有空间。

这个负结果值得记下来，因为它否掉了一整类想法：**精确商在这批实例上已经饱和。**

---

## 三、实验二：能量界恰好为零，所以它永远不触发

第二个猜想更自然。根层 ICC 在 held-out 上 0/50，但那是因为 ICC 只在根层做。**在每个节点上做**聚合能量检查呢？

对每个期限阈值 b，令 `S_b = {i∈R : d_i ≤ b}`。这些任务必须全部在 `[min_{i∈S_b} r_i, b]` 内完成，所以

```text
Σ_{i∈S_b} p_i  ≤  C(min r(S_b), b)
```

是必要条件。这叫 EPC（Energetic Prefix Cut），用前缀和可以 O(1) 算一个窗口。我把它放在 RSI 之前，跑 50 个 held-out 的 57,236 个节点：

**命中 0 次。**

我不信，于是直接量了根的松弛量：

```text
slack(b) = C(min r(S_b), b) − Σ_{i∈S_b} p_i
```

50 个根上，所有 b 的 slack **最小值恰好是 0，没有一个为负**。也就是说：根层的能量不等式是**紧的**，但不是**破的**。这不是实现问题，是结构问题——这些 NO 是纯粹的**整数性间隙**：连续松弛可行且几乎饱和，不可行性来自「任务不可拆分 + 机器不可同时开工」的离散性。任何单窗口容量不等式（ICC、EPC、EDF 预松弛、Hall 割）都只能看到连续松弛，所以它们在根层全部失效。

我在已展开的状态上又数了三种更-local 的条件（不剪枝，只统计违反次数）：

| 条件 | 违反节点数 / 57,236 |
|---|---:|
| 全任务可放置性 ATPF | 547（0.96%） |
| ready 窗口能量 RWE | 23 |
| ready 集聚合能量 | 16 |
| EPC（期限/释放扫描） | **0** |

这和 v2.5 的消融完全对上：ATPF 只省 2.1% 节点却要重扫全任务。**局部容量条件在这批数据上就是死的。** 想剪，必须剪「序」，而序的代价又回到每节点常数。

## 四、于是只剩机器：把节点变成一个词

图灵机的视角在这里给了正确的抽象：不要问「搜索策略还能怎么改」，要问「这台机器执行一个节点要几条指令」。v2.5 的节点里，最贵的是 `PLACE`：对 `[t, t+p_i)` 的每个槽做一次 shift/and/sub，p_i 最大 9，就是 9 次大整数循环。`AV`（可用槽位图）还要在每个槽上维护。

三个观察把它压成常数条**字**操作：

1. **PLACE 是一次减法。** 容量剖面 `CP = Σ_t c(t)·2^{cw·t}`，每个字段 cw 位。要占 `[t,t+p)`，就是减去 `rep[p] << (cw·t)`，其中 `rep[p] = Σ_{j<p} 2^{cw·j}` 是定值。因为 `EARLIEST` 只返回每个字段都 ≥1 的 t，**逐字段减 1 不会借位**，一次大整数减法就完成了全部 p 个槽。

2. **AV 不用存，可以导出。** 字段非零 ⟺ 字段里有一位是 1：

   ```text
   AV = (CP | CP>>1 | … | CP>>(cw−1)) & ONES
   ```

   `ONES` 在每个字段的最低位置 1。cw=2（m=3）时就是两次操作。**位图不是状态，是视图。**

3. **EARLIEST 用倍增找连续 1。** `p` 个连续可用槽不用 p−1 次 and，可以倍增：先合成长度 2 的 run，再 4、8，最后补一段 `p−L`。p≤9 时 4 次就够。

4. **memo key 是一个整数**：`CP | (RP << cw·h) | (mask << (cw·h+rw·n))`。字段定宽，单射，一次 int 哈希。

50 个 held-out，节点数完全不变（57,236），内核时间：

| 内核 | 节点 | 时间 | µs/节点 | 相对 v2.5 |
|---|---:|---:|---:|---:|
| v2.4 tuple OS | 80,463 | 0.4069 s | 5.06 | 2.06× 慢 |
| v2.5 packed | 57,236 | 0.1976 s | 3.45 | 1.00 |
| **WOS（本轮）** | 57,236 | **0.1265 s** | **2.21** | **1.56×** |

对 v2.4 是 4.11×。这一步没有任何算法思想，只有机器模型；但它是后面那一步的前提。

## 五、意外：forcing 翻盘了

v2.5 试过 singleton forcing：如果某个 ready 任务的**最早可行起点等于它的最晚允许起点**（`t_i = d_i − p_i`），那它在任何可行完成里都只能在这个时刻开工，可以直接提交、不用分支。它省 34.7% 节点，但每节点多 3.70 µs，而阈值是 2.29 µs，所以在 Python 里输。

关键的一点是：**这个测试几乎不要钱**。分支扫描本来就要为每个 ready 任务算 `t_i`；`t_i == d_i − p_i` 只是多一次比较。真正贵的是「提交之后要重扫 ready 集」。我在 WOS 里把它写成入口的 fixpoint：

```text
while True:
    key = K(mask, CP, RP)
    if key in seen: return NO          # ← 这一行是胜负手
    扫 ready，算 t_i；若有 t_i = d_i − p_i，提交它并 continue
    break
分支
```

第一版我把 `key` 放在扫描**之后**（因为 fixpoint 会改状态，看起来 key 该最后算）。结果：

| 内核 | 节点 | 时间 | ce |
|---|---:|---:|---:|
| 无 forcing，memo 在前 | 57,236 | 0.1302 s | — |
| forcing，memo 在扫描后 | 37,364 | 0.1431 s | 1.56 µs |
| **forcing，memo 在扫描前** | 37,364 | **0.0990 s** | **0.44 µs** |

把 memo 检查提到 fixpoint 顶部，`ce` 从 1.56 µs 掉到 0.44 µs，阈值 1.18 µs——**同一条规则从输 10% 变成赢 22%**。原因是：forcing 树的 37,364 个节点里有 17,869 个是 memo key，约 19,000 次命中；memo 在扫描后，每次命中都要付一次完整扫描。

这件事的方法论意义比数字大：**memo 检查的位置是算法的一部分，不是实现细节。** 它决定了「剪枝强度 vs 每节点常数」这条曲线上的一个点落在阈值哪一侧。v2.5 的命题 1 是对的，但它把 `ce` 当成了规则的属性；`ce` 其实是 (规则, 核心, 检查顺序) 的属性。

## 六、adaptivity 的负结果：门控不划算

既然 forcing 的收益和代价都在节点上，自然会想：只在**浅层**（子树大、省得多）开 forcing，深层关掉。这是最像「adaptivity」的一步。我测了 `dep < K` 的一族门：

| 门 K | 节点 | 时间 |
|---|---:|---:|
| 2 | 52,455 | 0.1235 s |
| 4 | 51,863 | 0.1214 s |
| 6 | 48,433 | 0.1143 s |
| 8 | 45,007 | 0.1080 s |
| 10 | 40,499 | 0.1013 s |
| 12 | 37,905 | 0.0995 s |
| 全开 | 37,364 | 0.0998 s |

曲线是单调的，全开最好（K=12 与全开在噪声内打平）。**门控没有收益**，因为「省下的子树」和「扫描的代价」都正比于同一个子树规模，比值与深度无关。adaptivity 在这里是一个伪维度——和 v2.5 发现的「NO 上顺序是死维度」同构。

## 八、这一轮我真正学到的东西

1. **先证伪再动手。** 「商状态」「加能量界」都是很自然的第一步，各花一次测量就否掉了。如果我先写 2,000 行再测，会得到同样的负结果，但浪费一轮。
2. **负结果要测量到「为什么」。** 能量界不是「效果不好」，是**根层 slack 恰好为 0**；这个解释直接排除了整个单窗口松弛家族，而不只是 EPC。
3. **常数不是脏话。** 在序不变性定理之后，NO 上已经没有策略空间；剩下的就是机器。把节点从 3.45 µs 压到 2.21 µs 之后，v2.5 判死的 forcing 重新变成 Pareto 改进。**同一个算法在不同常数下有不同最优配置**——v2.5 说过这句话，这一轮把它变成了一个可复现的翻盘。
4. **检查顺序是算法。** memo 在 fixpoint 前还是后，值 0.44 µs 的 `ce`，直接决定 forcing 的生死。这类「实现细节」在成本模型里就是一等公民。

---

## 九、一句话最大风险

**这一轮的 2.00× 内核加速里，真正算「算法」的只有 forcing 的 34.7% 节点，其余全是把 Python 循环换成大整数位运算；一旦换到 C，`ce` 和 `c0` 会一起缩小，forcing 的阈值关系可能再次翻转，而最坏情况的指数上界仍然一点没动。**
