# 想法区 · 第 4 轮：把「枚举」升成「割」——BFS 前缀树、双侧证书，以及「穷举」本身的下界

**灵感词**：复杂度下界 / 广度优先搜索 / 伪代码
**起点**：v2.2「X-DUB/PACE-ΠA-CP*」。它在第 3 轮用 5 个残例的根闭换来了 held-out 229→50，但收官风险仍然是一句话：

> CPS 用「枚举一条链的所有 placement + 精确 residual 回溯」换来了 5 个残例的根闭，但它的完备性只覆盖 `S≤4`、`n≤16`、全资格且 residual 未撞 cap 的紧状态；一旦 residual 变大或资格异构，它只能退回 unknown，最坏情况仍是 `d!`。

这句话里其实混着两个不同的东西：一个是**覆盖门**（`S≤4`、`n≤16` 这些参数），另一个是**证书本身的形状**。第 3 轮改的是前者——把「块」换成「链」，让紧凑状态有一个可枚举的粗变量。它没有碰后者：CPS 的证书永远是**叶子表**，一个 placement 一个叶子，叶子之上没有信息。于是：

- 它没有「部分进展」：要么枚举完所有 placement，要么 UNKNOWN；
- 它回答不了「这 106 个 placement 里有多少是真必要的」；
- 它更回答不了「换一个更强的检查能省多少」。

本轮不推倒 v2.2。我想把证书的形状从**叶子集**改成**割**。

## 一、直觉：前缀也是全称对象

一条链 `P=(i_1≺…≺i_L)` 的 placement 树：第 `t` 层是前 `t` 个链任务的起点 `(s_1,…,s_t)`，第 `L` 层是完整 placement。每个完整 placement 是根到叶的一条路径。

关键的一句话：

> **前缀也是全称对象**。每个完整 placement 唯一地穿过每一层的一个前缀；如果一个前缀已经和某个必要条件矛盾，那么它下面的整棵子树都不可能是可行排程。

所以证 NO 不必等到叶子。任何一个**割**（antichain：每条根—叶路径恰好碰一个节点）都是证书。v2.2 只是把割限制在了叶子层；而「限制在叶子层」正是它撞 `d!` 的原因。

两个实测的例子（详见产物区）：

```text
held-out idx 42：56 个 placement，BFS 割 38 个节点（只省 32%）
held-out idx 40：210 个 placement，BFS 割 47 个节点（省 4.5 倍，2.31×）
held-out idx 1 ：84 个 placement，BFS 割 41 个节点（省 2.0 倍，2.19×）
```

差别不在 BFS，而在**深度 1 的测试能不能看见矛盾**。

## 二、为什么是 BFS，而不是 DFS

DFS 也能剪枝，而且通常更省内存。选 BFS 有三个具体理由，都和下界有关：

**（1）层结束时的 frontier 是一个可检查的下界。** 第 `t` 层结束时，frontier 里每个「活」前缀（还能补成合法链 placement）都至少有一条完整延拓。任何割必须在这棵子树里放一个节点，而且不能是它自己（它通过了测试）。于是

```text
|任何 T-割| ≥ |活 frontier|，   割的深度 ≥ t+2 .
```

这把「跑不动了」从失败变成了**结果**：预算截断时返回的不是一句 UNKNOWN，而是一个可检查的下界。

**（2）证书变成双侧的。** 上界 = 找到的割，下界 = 活 frontier，gap 就是测试类 `T` 的不完备度。若 gap=0（割=placement 数），说明在这条链上、这个 `T` 下，任何算法都不可能更小——这是**实例级的复杂度下界**，不是渐近口号。

**（3）层级并行/anytime。** 第 `t` 层的节点互不依赖，可以整层并行；预算按层切，代价可预测。v2.2 的并行单位是 placement，被最慢的那个 residual 卡住（4 核只有 1.98×）；BFS 的并行单位是整层，Amdahl 项从「最慢 placement」变成「最宽层」。

## 三、复杂度下界的正确用法

我不想假装证明 P≠NP。能证明的是三件事：

- **上界**：任何 `T`-割 ≤ placement 数 `N`；`T=∅` 时 BFS-PC 逐字退化成 v2.2（割=叶子集）。
- **下界（实例级）**：活 frontier 数 ≤ 任何 `T`-割。所以当 frontier 一直活到叶子层时，割=`N`，BFS-PC 的证书在该 `T` 下**最优**。
- **barrier（族级）**：只要 `T` 在叶子之上的每个前缀都通过，割就必然等于 `N`。**held-out 的 49 个 NO 例里，30 个恰好如此**（cut=placement 数、零内部剪枝）。这不是构造出来的病态例子，是多数派。

这条结论解释了本轮一个不太好听的实测：49 个共同 NO 例上，精确 residual 的调用从 947 降到 585（−38%），residual 节点 4.83M→3.13M（−35%），但几何平均加速只有 **1.032×**（中位数 1.061×）。因为在 61% 的实例上，v2.2 的枚举**已经是这个证书族的最优解**；剩下的 39% 里省下的叶子，并不总是最贵的那些——总时间能到 1.47×，主要靠 case 40（210→47 个叶子，19.5→8.4 s）和 case 1（84→41，1.6→0.73 s）这几个大头。

它同时给出了下一轮的方向：**想再快，只能加强 `T`，不能改遍历顺序**。本轮顺手做了一个对照：给 `T` 加一个 clique 测试（窗口落在 `[a,b)` 内、`p>(b−a)/2` 的任务两两重叠，必须占不同机器），在构造的 barrier 族上把割从 10 压到 1；但在 held-out 上只从 505 压到 501（−0.8%）。加强测试是有方向的，但不是免费的。

## 四、伪代码：把 `T` 做成接口

整个框架只有一个可插拔的东西：`TEST(prefix)`。正确性只依赖它的**可靠性**（fail ⇒ 无延拓），不依赖它的强度。于是伪代码可以写成（完整版见产物区）：

```text
BFS-PC(σ, P, B):
    frontier ← {ε};  cut ← ∅
    for t = 0,1,… while frontier ≠ ∅ and budget > 0:
        for x in frontier:                     # 整层，可并行
            if |x| = L:
                if RESIDUAL(x) = NO: cut ← cut ∪ {x}
            else:
                for y in CHILDREN(x):
                    if TEST(y) = fail: cut ← cut ∪ {y}
                    else:             next ← next ∪ {y}
        frontier ← next
    return NO  if frontier = ∅ and no UNKNOWN
           UNKNOWN(cut, frontier, LB)  otherwise
```

这段伪代码的好处是：`TEST` 换成 `∅` 就是 v2.2；换成 window+ER 就是本轮；换成 window+ER+clique 就是更强的版本。所有定理对任意可靠的 `TEST` 成立。换句话说，**v2.2 是 v2.3 的一个特例**，而「加强测试」是一个可以逐格推进的实验轴。

## 五、形式化（简版；完整定义、证明与实现见产物区）

**定义 1（placement 树）**。节点是合法前缀 `x=(s_1,…,s_t)`；`y=x·(s_{t+1})` 是子节点当 `s_{t+1} ≥ s_t+p_{i_t}` 且 `s_{t+1}+p_{i_{t+1}} ≤ h−q_{i_{t+1}}`。叶子是完整 placement。

**定义 2（活前缀）**。前缀 `x` 是活的，若从 `x` 出发按最早优先能把链补完（贪心，链上无其它约束，所以贪心最优）。

**定义 3（T-割）**。`C` 是 `T`-割，若 (i) 每条根—叶路径有且仅有一个节点在 `C`；(ii) 每个 `c∈C` 被 `T` 判 fail（叶子则被 exact residual 判 NO）。`T` 可靠：fail ⇒ 该节点无可行延拓。

**定义 4（BFS-PC 的三值语义）**。`NO` 若割覆盖全部叶子且无 UNKNOWN；`YES` 若找到一条可行叶（全资格 + exact residual 时是构造性证明）；`UNKNOWN` 若预算/cap 截断。

**定理 1（可靠性）**。`T` 可靠 ⇒ `BFS-PC=NO` ⇒ `σ` 不可行。

**定理 2（包含 v2.2）**。`T=∅` 时，BFS-PC 的割 = CPS 的叶子集；两者判决相同。

**定理 3（双侧下界）**。第 `t` 层结束时的活 frontier `L_t` 满足：任何 `T`-割 `|C| ≥ |L_t|`，且 `C` 含一个深度 `> t+1` 的节点。

**定理 4（barrier 与最优性）**。若 `σ` 不可行且 `T` 在所有内部前缀通过，则割恰为全部 `N` 个叶子；此时 BFS-PC 的证书在该 `T` 下最优，且任何同 `T` 算法至少要跑 `N` 次叶判定。

**定理 5（并行/anytime）**。层内节点独立；预算截断返回 `(cut, L_t)` 双侧证书。

## 六、本轮要交付什么

- **v2.3 = v2.2 + BFS-PC（tier 0.15）**：`CPS` 成为 `TEST=∅` 的特例，`BFS-PC` 是它的割版本。
- **双侧证书**：割（上界）+ 活 frontier（下界），都带独立检查器。
- **实测**：held-out 50 的 49 个共同 NO 例，精确 residual 调用 947→585（−38%），residual 节点 4.83M→3.13M（−35%），总时间 80.2→54.4 s，几何平均 1.032×，30/49 例割=placement 数（barrier 见证）；5 个残例割 7/12/21/38/7 vs placement 7/15/21/56/7；随机 60 状态 0 假 NO/0 假 YES；S≥5 合成 10 例在 v2.2 门外、BFS-PC 在根节点 1 步闭（ER off 时是 126 个叶子）。
- **负结果**：clique 在 held-out 上几乎无效；临界路径可能退化成 `L=1`（单个大任务），这时 BFS 没有内部结构可剪；barrier 只对 `TEST=window+ER` 成立。

## 七、一句话最大风险

**本轮最大的风险不是「BFS 没用」，而是把 30/49 的 barrier 误读成「证书族已经到顶」：barrier 只对 `TEST=window+ER` 成立，换一个测试就可能塌掉；而「加强测试」这件事目前没有理论指导，只能一个个试。**
