# 想法区 · 第 4 轮：证明的长度就是状态集——三次「缩小 E」的否证，和一台把 E 拿出内存的分层前沿证明器

**灵感词**：循环不变式 / 剪枝 / out-of-core algorithm
**起点**：v3.0「X-DUB/PACE-ΠA-WOS」。它在 50 个 held-out 上把内核从 0.1976 s 压到 0.0990 s（2.00×），节点 57,236→37,364（forcing 贡献 −34.7%），峰值常数 2.65 µs/节点。它的收官风险是一句话：

> 这一轮的 2.00× 里，真正算「算法」的只有 forcing 的 34.7% 节点，其余全是把 Python 字段循环换成大整数位运算；一旦换到 C，`c0` 与 `ce` 会一起缩小，forcing 的阈值关系可能再次翻转，而最坏情况的指数上界仍然一点没动。

这句话我完全同意，但它把下一轮的方向指错了。它暗示「下一个因子还得靠更便宜的常数」；我这一轮先问了一个更硬的问题：**这棵树的 37,364 个节点里，到底有多少个是「真的状态」，有多少个只是哈希表的回声？** 答案把整轮的方向翻了过来——37,364 里有 19,495 个是 memo 命中，真正的展开只有 17,869 个（命中率 52.2%）。v3.0 的「µs/节点」把两种完全不同的东西平均在了一起。

于是这一轮做了三件事：

1. 先把「能不能把状态集 E 缩小」这件事**测量到死**：同 mask 支配只能合并 5.5%，最小不可行核是 n−1（不是小证书），方向选择不可预测。三条都否掉。
2. 既然 E 缩不小，就**不要再把 E 存在内存里**：把 DFS 换成按层推进的前沿证明器（LFP）。它的循环不变式是「第 k 层前沿恰好是恰好排了 k 个任务的可达状态集」，因此**不需要 `seen` 表**，也**不需要回头**。
3. 把「方向」当成一个定理而不是启发式：时间反演是精确对偶，LFP 在两个方向上判决相同、状态数不同；本批数据上反向更小。

结果是：判决完全不变，调用 37,364 的 DFS 被换成 19,117（前向）/15,466（反向）次纯展开，内核时间 0.1032→0.0971/0.0895 s，**逐例双峰驻留中位降 2.50×（最大 18.2×，1 例反超到 0.75×）；最大单例 2,109→670，最宽层 365**。这不是一个大的时间因子；它是一个**内存因子的换轨**（内存版 O(W)，外部版 O(B)），而且是这一轮唯一没有被三次否证堵死的方向。

---

## 一、先把「节点」拆开：37,364 = 17,869 次展开 + 19,495 次回声

v3.0 的 WOS 是一个带精确 memo 的 DFS。对 NO 实例，引理 0 说每个可达节点都不可行，所以每个状态最终都会被 `seen` 记住。把 50 个 held-out 的统计拆开：

```text
调用（节点）        37,364
memo key（= 状态）   17,869          ← 展开数
memo 命中            37,364 − 17,869 = 19,495   ← 52.2%
RSI 死亡              7,064          ┐
分支节点             10,805          ┴ 7,064 + 10,805 = 17,869
forced 提交           5,055
```

最后一行是一个漂亮的恒等式：**展开 = 分支 + RSI 死亡**（17,869 = 10,805 + 7,064），没有一个展开是「既没分支也没报死」的。而 19,495 次命中不是状态，是同一个状态被不同路径第二次、第三次走到。v3.0 的序不变性定理说，NO + 精确 memo 时调用数 = 1 + 可达状态图的边数；对这批树，平均每个状态被走到 2.09 次（1 次展开 + 1.09 次命中）。**每一次命中都要付一次递归调用、一次大整数 key 构造、一次哈希查找**；v3.0 把这些都算进了「2.65 µs/节点」，于是一个真实的展开和一个哈希回声被平均成了同一个数。

> **口径修正**：这一轮所有比较都用 **expansion**（真正展开一个状态）而不是 node（进入一次 dfs）。37,364 个 node 里有 17,869 个 expansion、19,495 个命中；LFP 的 19,117（前向）就是这个口径下的同一个量。

这一步本身不产生算法，但它决定了后面两个问题的提法：E=17,869 能不能变小？如果变小不了，能不能不把 E 放进内存？

---

## 二、否证一：同 mask 支配只能合并 5.5%，因为 memo 已经是反链

最自然的「缩小 E」是支配。同 mask 下，若状态 A 的容量剖面逐点 ≥ B、释放向量逐点 ≤ B，则 B 的每个完成也是 A 的完成，所以 A 是 NO ⇒ B 是 NO。v2.9 在 tuple 核上试过（`os_dom.py`，guard-bit 逐字段比较），节点 80,463→74,301（−7.7%），时间 0.511→1.713 s（3.35× 慢）。当时归因于「Python 前扫太贵」。

我先不重复实现，而是**直接量这批数据的可合并上界**：把 50 个实例的 17,869 个 NO key 解码成 `(mask, CP, RP)`，按 mask 分桶，算每桶的 Pareto 反链。

| 指标 | 值 |
|---|---:|
| NO 状态总数 | 17,869 |
| 被同 mask 状态支配 | **991（5.5%）** |
| 不同 mask 数 | 7,097 |
| 每桶反链均值 | 2.28 |
| 最大单桶反链 | 1,020 |

两个读数：

- **上界只有 5.5%**。即使支配检查免费、即使被支配的状态子树全部省掉，E 也最多从 17,869 降到 16,878。按 ~5.8 µs/expansion 算，最多省 6 ms。
- **反链均值 2.28，但有一个桶 1,020**。这说明「前扫」在平均情况下便宜、在最坏情况下极贵；v2.9 的 3.35× 就是这么来的。批量做（按层排序后线性扫）能摊平，但收益上界仍然只有 5.5%。

结论：**memo 本身已经近似是一条反链**。这不是实现问题，是这批实例的状态图结构：同一个 mask 下能到达的 `(CP,RP)` 组合几乎两两不可比——容量多的往往释放晚，二者反向相关。想靠支配把 E 砍半，没有空间。

## 三、否证二：最小不可行核是 n−1，NO 没有小证书

第二个自然的想法是「小证书」：如果每个 NO 实例都含一个很小的子集，它自己就不可行，那我们只要找到这个核，就能在根部用几行证书结案，根本不用搜 17,869 个状态。

我用贪心 1-极小化直接量了核的大小。对每个 NO 实例，从全集开始，依次尝试删掉每个任务；若删掉后**子实例仍然不可行**（子实例 = 优先图限制在子集上、`est/q` 重算、同一个 h），就永久删掉。得到的是一个 1-极小核（删任何一个都变可行）。

| 核大小 | 实例数 |
|---|---:|
| n（删不掉任何任务） | **20 / 50** |
| n−1 | 15 |
| n−2 | 9 |
| n−3 | 4 |
| n−4 | 1 |
| n−5 | 1 |

中位数是 **n−1**，最小也只到 n−5（n=15 时核=10）。也就是说：**这批 NO 没有小证书**。`h=OPT−1` 是一个「差一个单位」的全局边界，几乎每个任务都参与了这个单位——删掉任何一个，剩下的就能塞进去。

这解释了为什么 v3.0 的 ICC/EPC 在根层 0 命中、为什么根层 slack 恰好为 0：不是证书不够强，是**根本不存在一个局部的小反例**。任何「先找一个小核，再用小核结案」的算法族，在这批数据上都是死的。这个负结果比「支配只有 5.5%」更强：它说的不是「合并得少」，而是「不可行性本身是全局的」。

## 四、否证三：方向是真维度，但不可预测

第三个想法来自「如果 E 是证明长度，那换个方向枚举，证明会不会短」。时间反演是精确的：把优先图反向、`est` 与 `q` 互换、`h` 不变，得到一个对偶实例；原实例可行当且仅当对偶实例可行（把每个开始时刻 `s_i` 映到 `h−s_i−p_i`）。

在 DFS+forcing 上直接量：

| 方向 | 节点 | 时间 |
|---|---:|---:|
| 前向 | 37,364 | 0.1032 s |
| 反向 | 28,251 | 0.0964 s |

反向在 28/50 个实例上更小，总量 −24.4%。看起来很香。但把逐例比值摊开：

```text
bwd/fwd 比值：最小 0.117（case 31: 492→64）
              最大 4.21 （case 15: 57→240）
              28 个 < 1，22 个 > 1
```

也就是说，方向是一个**方差极大的随机变量**，不是一个可以静态选对的参数。我试了 `sum est`、`sum q`、`sum est−sum q`、`max est−max q`、`n` 等特征去预测 `log(bwd/fwd)`，最好的一维相关系数只有 −0.214，`n` 是 0.02。又试了「先用小预算跑一个方向，失败再换另一个」的单次探测：

| 探测预算 C | 反向探测+前向 | 前向探测+反向 |
|---:|---:|---:|
| 50 | 39,658 | 30,566 |
| 100 | 40,503 | 32,633 |
| 300 | 45,245 | 37,886 |
| 800 | 36,054 | 35,458 |
| 1200 | 33,850 | 36,936 |

没有一个配置打败「直接反向」的 28,251。原因是：探测的浪费是**每个实例都付**的，而方向的收益是**只在那些方向差很大的实例上**才兑现；两者的期望对不上。

所以方向这件事的正确用法不是「预测」，而是「**让算法本身与方向无关，然后选一个默认**」。这一轮选反向做默认（本批数据上它更好），但把它写成参数，并在风险里明说这是分布相关的。

## 五、转轴：如果 E 缩不小，就不要把 E 放进内存

三次否证之后，剩下的路只有一条：**E 就是证明长度，那就让证明流过去，而不是把它堆在内存里**。

DFS 的 memo 是「历史」：为了判断一个状态是否来过，它必须记住所有展开过的状态。但注意，DFS 的展开顺序是任意的；如果我们**按「已排任务数」分层推进**，那么一个状态只可能从第 k 层到第 k+1 层，**永远不需要回头看第 k−1 层**。这就是循环不变式的位置：

```text
F_0 = {根}
F_k = { 一步合法放置后的状态 : σ ∈ F_{k−1} }   （层号按实际已排任务数；去重、RSI 死掉的丢掉）
```

不变量：**处理完第 k 层后，F_k 恰好是「恰好排了 k 个任务」的全部可达状态**（在 forced 闭包下）。于是：

- 不需要 `seen` 表。去重只在层内做。
- 不需要递归栈。层与层之间只有 `F_k` 一个文件。
- **F_k 可以顺序写在磁盘上**：子状态流式产生、排序、归并去重；上一层的文件读完就可以删。峰值内存是「最宽的一层 + 排序缓冲」，不是 E。

这就是三个灵感词的交点：**循环不变式**给出「可以忘掉历史」的许可证；**剪枝**（RSI + forcing）原样保留在每一层；**out-of-core** 不是把 DFS 的 memo 搬到磁盘（那是随机 I/O），而是把**层**当成外部对象（顺序 I/O）。

一个实现上的关键点：forcing 不能在层里「多算一个状态」。若状态 σ 有唯一可行起点的任务 i，就在**同一次展开内**提交它、继续 fixpoint，直到没有 forced 任务才把结果写进它该去的层。这样 forced 链不会在 F 里留下中间状态，层状态数才等于真正的状态数。

## 六、度量：展开数、时间、峰值常驻

50 个 held-out（h=OPT−1，全 NO），同一进程、交错 4 次取中位数：

| 内核 | 调用 / 展开 | 时间 | 常驻峰值（最大 / 中位） |
|---|---:|---:|---:|
| DFS 前向（v3.0） | 37,364 / 17,869 | 0.1032 s | 2,109 / 211 |
| DFS 反向 | 28,251 / 14,515 | 0.0964 s | 1,578 / 215.5 |
| **LFP 前向** | — / **19,117** | **0.0971 s** | **1,098 / 74.5** |
| **LFP 反向** | — / **15,466** | **0.0895 s** | **670 / 75.5** |

读数：

- 相对 v3.0：前向 1.063×，反向 **1.153×**（方向单独 1.071×、层化单独 1.063×，叠加近可乘）。时间因子不大，因为 DFS 的 19,495 次命中本来就是便宜的（~0.5 µs），LFP 省掉的是这笔「回声税」，不是展开本身。
- 展开数：前向 19,117 比 DFS 的 17,869 **多 7%**（多出的部分是 forced 前置状态：DFS 不把它们记进 `seen`，LFP 把它们当成层状态展开一次）；反向 15,466 比 DFS 少 13.4%。**层化本身不减少展开，它减少的是「为了去重而必须记住的历史」和 19,495 次命中调用。** 反向的 −13.4% 是方向的红利，不是层化的红利——这一点必须说清楚。
- 峰值常驻：DFS 行是 memo key 数，LFP 行是双峰驻留 `|F_k|+|F_{k+1}|`。逐例比值中位 2.50×、最大 18.2×、**最小 0.75×**（case 15：44 个 memo 反而比 59 的双峰小）。最大单例 2,109 → 670；最宽层只有 365。这是这一轮真正大的那个数，但它不是普适的。

正确性：

- 1,260 组随机小实例（n=3–7、m≤4、h=3–12，649 可行）对暴力枚举，前向/反向两条路径都测，**0 不一致**。
- 50 个 NO + 50 个 YES（h=OPT）对 WOS 判决，两个方向各 100 次，**0 不一致**。
- 反向对偶的判决与前向完全一致，验证了 §4 的映射。

YES 侧是一个明确的坏消息：

| h=OPT（YES） | 时间 | 展开/节点 |
|---|---:|---:|
| DFS+forcing | **0.0130 s** | 3,743 |
| LFP 前向 | 0.1499 s | 31,032 |
| LFP 反向 | 0.1518 s | 约 31k |

LFP 在 YES 上慢 11.5×。原因很本质：DFS 是**找解器**，找到一条路径就停；LFP 是**证明器**，必须把每一层铺满才能知道全掩码那一层有没有状态。所以这一轮不把 LFP 当成 WOS 的替代，而是把它当成级联里的**NO 证明器**：YES 仍走 DFS 的早停，NO 走 LFP。v3.0 的缓存、ICC、级联门全部不动。

## 七、这一轮我真正学到的东西

1. **先把度量拆开，再谈优化。** 37,364 个「节点」里有 19,495 个是哈希回声，真正的展开只有 17,869。v3.0 的 2.65 µs/节点是一个把展开和命中混在一起的指标；拆开之后，才知道「减少节点」和「减少工作」不是一回事。
2. **负结果要测量到「为什么」。** 支配不是「效果一般」，是 **memo 已经是反链**（均值 2.28）；核不是「不容易找」，是 **20/50 的核就是全集**；方向不是「有噪声」，是 **逐例比值 0.12–4.21、没有廉价预测器**。这三句话各自排除了一个算法族，而不只是三个参数。
3. **循环不变式不只是正确性工具，还是内存定理。** 「第 k 层只依赖第 k−1 层」这句话的推论是「可以忘掉 k−1 以前的一切」，也就是 out-of-core 的许可证。正确性和内存在这里是同一个命题的两个面。
4. **不是所有状态都值得存在内存里。** 最大单例 2,109 个 memo key 的证明，双峰驻留只有 670（最宽层 365）；峰值由「最宽的一层」决定，而不是由「总共见过多少」决定。这对 NO 证明是结构性的，对 YES 找解不是（要找解就得记住路径）。
5. **方向是定理，不是启发式。** 时间反演是精确对偶，所以「换方向」永远是合法的；但它是不是划算，是一个分布相关的事实，不能靠一个静态预测器包打天下。

---

## 八、一句话最大风险

**这一轮的 1.15× 时间收益主要来自「反向恰好更小」这个分布事实，层化本身只贡献了约 6%；而峰值内存的中位 2.50× 是「不存历史」换来的，一旦换到 YES 侧或需要重建路径，这份内存又会以父指针的形式回来。**
