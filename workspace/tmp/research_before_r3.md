# 想法区 · 第 1 轮：从「数块」到「配机器」

**灵感词**：编译器优化 / 归约 / postcondition
**起点**：v2.0「X-DUB/PACE-Λ*」。38 例 88 节点 / 23 表，deep 8 例 223 / 115，held-out 50 例 1,935（32 胜 18 平 0 负），easy 60 例 781。它的收官风险是一句话：

> DHD 与 RHD 是同一个盒子的两个面：当一层 ready 任务同步释放时两个面同时失效，分支因子仍是 d，最坏情况仍是 n!。

本轮不推倒 v2.0。我想把这句话再往前推一格：**如果顺序规则真的走到头了，那么下一个该被用掉的结构是什么？**

## 一、墙后面不是「更细的顺序」，是「装填 + 分配」

v2.0 的 DHD 只读每个任务盒子的两个端点 `est_i, lst_i`。它是一条**局部顺序**规则：若 j 比某个更早的任务释放得晚，j 就不可能是第一个。同步层上所有 `est` 相等，`μ ≥ e`，于是 `K = Ready`。这不是证明不够精细，而是盒子在这层退化成同一个点：`est/lst` 里已经没有顺序信息。

真正的问题不是「谁先」，而是「这一层 d 个任务到底能不能被 m 台机器装下，并且每块都装在对的机器上」。最小形状：m=2，三个 p=4 的任务都在 [0,10] 里；任何顺序规则都保留三个，但两台机器最多装两个 4。这需要的是**装填**证书，不是顺序证书。

最自然的装填证书是单机划分数 `β(R)`：把 R 划分成最少的单机可行块，若 `β(R)>m` 则 NO。它是可靠的，而且在 hard3#5 / deep 上极强。但它有一个我在 large_het#1 上撞到的洞：

> **β 只数「块」，不数「机器」。**

两个块可以都只 eligible 于 machine 0；或者 machine 1 要到时刻 5 才空。β 把它们当成两个可并行的块，于是 `β≤m` 说「可行」，可现实里没有足够的**不同**机器去接它们。large_het#1（n=15, m=3, h=39）就是这样一个真实反例：`β=3`，块数证书说「三块正好三台机器」，但 MAP 说 NO；v2.0 要 21 个节点，v2.1 在根上 1 个节点闭合。

所以本轮的攻击对象从「任务对之间的先后」换成「**块到机器的匹配**」。

## 二、直觉：一台机器的一个块，就是一个 postcondition

对状态 `σ=(R,A,est)`，固定机器 k 和一个任务集 S。把「机器 k 在 `A_k` 之后、按优先序、在窗口 `[est_i, h-q_i]` 内、只用资格 k，做完 S」的最早完工记为 `f_k[S]`。它由 Held-Karp 型递推给出：

```text
f_k[∅] = A_k
f_k[S] = min_{ i∈sink(S), k∈E_i }  max(f_k[S\{i}], est_i) + p_i
         要求  max(...) + p_i ≤ h - q_i .
```

`f_k[S] ≤ h` 就是「机器 k 完成 S」的 **postcondition**：只要这个式子成立，S 在 k 上就有一个合法的单机排程；反之，任何合法排程的最后一个任务都给出这个递推的一个候选，所以 `f_k[S]` 是最早完工，不是启发式。

现在把 m 台机器的 postcondition 组合起来：

```text
MAP(σ) = 1   iff   存在划分 R = S_1 ⊔ … ⊔ S_t (t≤m)
                   和单射 φ:{1..t}→[m]，使 f_{φ(j)}[S_j] ≤ h 对所有 j 成立。
```

**可靠性一句话**：任一从 σ 出发的可行排程，按机器把 R 分成 `S_1,…,S_m`；第 k 台机器的实际顺序就是 `f_k[S_k]` 的一个可行解，所以 `f_k[S_k]≤h`。于是 MAP 是可行性的**必要条件**；`MAP=0` 是 NO 证书。

注意方向：**MAP=1 不是可行性的证明**，只是「没有找到装填/分配矛盾」。它是 relaxation，不是 decision procedure。这一点决定了本轮所有定理的形状。

## 三、归约：从 m 机调度到「带机器身份的划分」

把上面的必要条件写成归约：

```text
SCHED(σ)  ⇒  ASSIGN(σ) ,
ASSIGN(σ) = 存在上述 (S_j, φ) .
```

`ASSIGN` 是一个**带机器身份的集合划分**问题：每块先在自己的机器上编译成一个 postcondition `f_k[S]≤h`，再要求这些块能被**不同的**机器接住。它比「数块」多了一层匹配，正是 large_het#1 缺的那一层。

这个归约是**严格的**：`ASSIGN` 可以成立而 `SCHED` 不成立，因为块与块之间的时间耦合（i 在块 A、j 在块 B、i≺j）被完全丢掉了。所以 MAP 只能杀「装填/资格/可用时间」型的不可行，杀不了「跨块顺序」型的不可行。held-out 的 5 个残例就是后者。

## 四、编译器优化：把 3^n 花在根上，而不是花在搜索树里

「编译器优化」在本轮不是比喻，它对应四个具体动作：

1. **profile compilation**：把一台机器对 S 的执行编译成一张 `f_k[S]` 表，而不是在搜索树里逐任务模拟。这是把 `m` 机交错搜索**强度削弱**成「单机 profile + 划分/匹配」。
2. **common subexpression elimination（CSE）**：若两台机器有相同的 `A_k` 和相同的资格列，它们的 `f_k` 完全相同，只算一次。全资格 + 同 A 的根上，m 台机器退化成一台，DP 也从「机器子集」退化成「已用机器数」。实测 n=16 的根上 0.3323 s → 0.0893 s（3.72×）。
3. **dead machine elimination**：`A_k>h` 或对 R 中任何任务都不 eligible 的机器直接删掉；不可行块直接跳过。
4. **slicing / partial evaluation**：n>16 时不对整个 R 算 MAP，而是取密度前 w 个任务做见证 W；`MAP(W)=0 ⇒ MAP(R)=0`。这把 3^R 换成 3^w。

代价是**每次调用 3^n**（或见证的 3^w），不是多项式。但它只在 `slack0≤4` 且 `n≤16` 的紧状态上跑；松状态和 easy 集上一次都不跑。最坏情况仍是 n!，只是把指数从搜索树搬到了根上的证书。

## 六、边界：MAP 是松弛，不是判决

这一轮最重要的负结果不是「哪里又赢了」，而是**MAP 在哪里必然失效**：

- **5 个 held-out 残例**：β=3、MAP=1，但 h=OPT−1 真的不可行。它们的不可行来自跨块优先序，不是装填，也不是资格。MAP 只能说「三块能配给三台机器」，说不出「这三块不能同时按这个顺序排」。
- **没有短证书**：MAP 的 NO 需要检查器重跑 3^n 的 DP，不像 LP 对偶那样有 O(n) 的证书。它是「可重放」，不是「短」。
- **n>16 的见证是启发式**：选不中就退回 v2.0；planted 上 21/21 命中，但那是因为 decoy 松弛、密度排序自然能挑到硬核。
- **时间不是免费的**：38 3.6×、deep 4.1×、held-out 4.3×；对根下界已经接近 OPT 的实例，MAP 是纯开销。
- **一个继承来的硬门**：v1.6 的非延迟机器支配 `omd` 只在全资格时成立；异资格实例必须 `omd=False`，否则会假剪。MAP 本身不依赖 `omd`，但主配置必须写对。
- **一个差点发货的 DP bug**：我最初用「机器集合的并」当状态，把 `{0}` 和 `{1}` 的并记成 `{0,1}`，于是 hard3#3 在 `h=OPT` 上被假 NO。正确做法是状态为「机器子集的**集合**」（bitset over `2^m`），不是并。这个 bug 提醒我：证书核的 DP 比搜索更容易写错，必须用暴力对拍。

## 七、一句话最大风险

**MAP 把「数块」升级成「块到机器的匹配」，但它仍然忽略块与块之间的时间耦合：当不可行性来自跨块优先序而不是装填/资格时，MAP 只能说 YES，搜索仍要回到 d!；5 个 held-out 残例就是这条边界。**

## 0. 版本关系与本轮增量

v2.0 的资产全部保留：`DHD`、`DCD`、`ODOM`、`HPACK`、`PACK-front`、`LC-PACK` 的 0/0.5/1/2/3 层、`LC-DEC`、`CHECK-LC`、`PROFILE`、`(est,A)` Pareto 前沿 `G`、孪生机器商 `CANON`、`FRONT`/`FRONT-SUB`/`NO-INT` 证书、`MINT`、`PACK-SET`、`SOP`、carry 定理。

本轮增量只有一条规则和一组围绕它的工程/负结果：

1. **`MAP`（tier 0.10）**：对每台机器 k 编译单机 postcondition 表 `f_k[S]`；若不存在把 `R` 划分成块、并把块单射到不同 eligible 机器的方案，则 `σ` 为 NO。
2. **严格强于「数块」**：单机划分数 `β(R)` 只数块，不数机器。`MAP` 要求块到机器的**单射匹配**；在异资格或 `A_k` 不同时严格更强。`large_het#1` 是真实分离例：`β=3`，`MAP=NO`。
3. **归约语义**：`SCHED(σ) ⇒ ASSIGN(σ)`。`ASSIGN` 是带机器身份的划分；`MAP=0` 是可靠的 NO 证书，`MAP=1` 只是「未知」，不是可行性证明。
4. **postcondition 语义**：`f_k[S] ≤ h` 是「机器 k 在窗口内做完 S」的 postcondition；划分 DP 是 postcondition 的组合规则。
5. **编译器优化**：profile compilation（单机摘要）、CSE（同 `(A_k,E_k)` 的机器共享 profile）、dead-machine elimination、witness slicing（n>16 取密度前 15 个任务）。CSE 实测把 held-out 时间从 6.31 s 降到 2.28 s（2.76×）。

## 2. 形式定义

### 2.1 状态与窗口

状态 `σ=(R,A,est)` 的语义与 v2.0 相同：`R` 是未调度任务，`A_k` 是机器 k 的空闲时刻，`est_i` 是 i 的最早开始下界。任务 i 的窗口是

```text
[ est_i , h − q_i ] .
```

`sink(S)` 是 S 内无后继的任务；一个合法单机顺序的最后一个任务必在 `sink(S)` 中。

### 2.2 单机 postcondition `f_k`

**定义 1（单机 profile）**。对机器 k 和 `S⊆R`，

```text
f_k[∅] = A_k
f_k[S] = min_{ i∈sink(S), k∈E_i }  max(f_k[S\{i}], est_i) + p_i
         要求  f_k[S\{i}] < ∞  且  max(...) + p_i ≤ h − q_i .
```

若没有候选，`f_k[S]=∞`。

**引理 1（f_k 正确性）**。`f_k[S]` 等于「机器 k 从 `A_k` 起、只做 S、按 ≺、满足释放 `est`、期限 `h−q`、资格 k」的最早完工时刻；若不存在这样的单机顺序，`f_k[S]=∞`。

**证明**。对 `|S|` 归纳。

- 任一可行单机顺序的最后一个任务 i 必是 `sink(S)`（否则 i 有后继在 S 内，不可能最后），且 `k∈E_i`。删去 i 后，前缀是 `S\{i}` 的可行顺序，完工不早于 `f_k[S\{i}]`；把 i 放在 `max(f_k[S\{i}], est_i)` 开始不会更差。所以真实完工 ≥ 递推候选的最小值。
- 反过来，对每个 sink i，若 `f_k[S\{i}]<∞`，把 i 接在最优前缀后就是一个合法顺序（优先、释放、期限、资格逐项成立）。取 min 即得。∎

注意 `f_k[∅]=A_k`：空块不是「0 时刻完成」，而是「机器在 `A_k` 就绪」。这使 `f_k` 能区分「机器早空」和「机器晚空」，也是 MAP 比 β 多出来的信息。

### 2.3 MAP：带机器分配的划分

**定义 2（可行块）**。`(k,S)` 是可行块，若 `S≠∅`、`k∈E(S)`、`f_k[S]<∞`。

**定义 3（MAP）**。

```text
MAP(σ) = 1  iff  存在 t≤m、划分 R = S_1 ⊔ … ⊔ S_t、
                  单射 φ:{1..t}→[m]，使 (φ(j), S_j) 是可行块对所有 j。
```

等价地：把 R 划分成块，给每块分配一台**不同**的 eligible 机器，使每块在该机器上的单机 profile 不超过 h。

**引理 2（必要性）**。若从 σ 出发存在可行排程，则 `MAP(σ)=1`。

**证明**。取任一可行排程。令 `S_k` 是排程中分配给机器 k 的任务集（空集允许）。则 `S_1,…,S_m` 是 R 的一个划分；每台机器的实际执行顺序是 `S_k` 的一个合法单机顺序，且 `k∈E_i` 对所有 `i∈S_k` 成立。由引理 1，`f_k[S_k] ≤` 该机器最后一个任务的完工 `≤ h`。取 `φ(k)=k`，去掉空块，即得一个合法分配。∎

**定理 1（MAP 可靠性）**。若 `MAP(σ)=0`，则从 σ 出发不存在可行排程。因此 `MAP=0` 是 NO 证书。

**证明**。引理 2 的逆否。∎

**方向说明（必须写进规格）**：`MAP(σ)=1` **不**蕴涵可行；它只是「没有找到装填/分配矛盾」。MAP 是 relaxation，不是 decision procedure。所有剪枝只允许在 `MAP=0` 时发生。

### 2.4 与「数块」β 的关系

**定义 3（β）**。

```text
β(R) = min { t : R = S_1 ⊔ … ⊔ S_t ,
              ∀j ∃ k_j∈E(S_j) 使 f_{k_j}[S_j]<∞ } ,
```

它只数块，不要求 `k_j` 两两不同；在机器孪生时这就是单机划分数。

**定理 2（MAP 在孪生机器上退化为 β）**。若所有机器有相同的 `A_k`，且对每个任务 i，`E_i` 要么是全机器集、要么为空（机器孪生），则

```text
MAP(σ)=1  ⇔  β(R)≤m .
```

**证明**。

- `⇒`：MAP 的划分本身就是 β 的一个可行划分，块数 ≤m，所以 β≤m。
- `⇐`：取 β 的最优划分 `S_1,…,S_t`（t≤m）。因为机器孪生，每个块可以分配到任意一台机器；把 t 个块单射到 t 台不同机器即可。∎

**定理 3（严格分离）**。存在状态使 `β(R)≤m` 但 `MAP(σ)=0`。

**证明（两个分离例）**。

1. **资格分离（真实基准 large_het#1）**：n=15，m=3，h=39。根上 `β=3`，但 MAP 的分配 DP 返回 0：资格集把某些块锁在同一台机器上，三块无法单射到三台机器。v2.0 在该状态要 21 个节点，v2.1 在根上 1 个节点闭合。
2. **可用时间分离（最小例）**：m=2，h=10，A=(6,0)，四个 p=4 的任务，全资格、无优先。β：两台机器各做两个 4（8≤10），β=2≤2。MAP：machine 0 只能做一个（6+4=10，两个就 14>10），machine 1 最多做两个（8≤10），总共最多 3 个任务 <4，所以 MAP=0。该状态确实不可行。

∎

**意义**：β 是「块数」证书，MAP 是「块数 + 机器匹配」证书。两者的差距不是常数因子，而是**量词**：β 说「存在三块」，MAP 说「存在三块和一个单射」。large_het#1 说明这个差距在真实基准上会发生。

### 2.5 见证（n>16 的 slicing）

**定义 4（见证）**。对 `W⊆R`，`MAP(W)` 用同一 `f_k` 定义，只是把任务限制在 W。

**引理 3（单调性）**。若 `W⊆R`，则 `MAP(R)=1 ⇒ MAP(W)=1`。

**证明**。取 R 的一个合法分配 `(S_j,φ(j))`。令 `S'_j = S_j ∩ W`；去掉空块。每个 `S'_j` 是 `S_j` 的子序列（删去不在 W 的任务），仍是机器 `φ(j)` 上的合法单机顺序（优先、释放、期限、资格对子序列封闭），所以 `f_{φ(j)}[S'_j]<∞`。不同块仍分配到不同机器。因此 W 有合法分配。∎

**推论 1（见证可靠性）**。若 `W⊆R` 且 `MAP(W)=0`，则 `MAP(R)=0`，即 σ 不可行。

**见证选择**：按密度 `p_i / max(1, h−q_i−est_i)` 取前 w 个（默认 15）。这是启发式；选不中只损失剪枝，不影响可靠性。

### 2.6 触发门

**定义 5（紧状态）**。

```text
lb0 = max( max_{i∈R}(est_i+p_i+q_i), ceil(Σ_{i∈R}p_i / m), max_{i∈R}p_i )
slack0 = h − lb0 .
```

MAP 只在 `slack0 ≤ map_tau`（默认 4）且 `|R|≤map_ncap`（默认 16）时跑；n>16 时只跑 w=15 的见证。门是**覆盖率**参数，不是可靠性参数：门关掉只会少剪，不会多剪。

## 3. 算法

### 3.1 每机器 profile 的编译

```text
COMPILE_PROFILE(k, rem, p, est, q, succ, elig, A, h):
    N ← 1<<|rem|;  f[0] ← A_k
    for S = 1..N-1:
        best ← ∞
        for i in sink_local(S):
            if k ∉ E_i: continue
            if succ[i] & S: continue
            if f[S\{i}] = ∞: continue
            st ← max(f[S\{i}], est_i)
            en ← st + p_i
            if en ≤ h − q_i:  best ← min(best, en)
        f[S] ← best
    return f
```

时间 `O(|R| 2^{|R|})`，空间 `O(2^{|R|})`。

### 3.2 划分/分配 DP

**单类（所有机器孪生）**。此时只需记「用了几台机器」：

```text
cover[0] ← 1                     # bit c = 用 c 台机器可达
for S = 1..N-1:
    low ← S & −S;  i0 ← ctz(low)
    res ← 0
    for block ⊆ S with i0∈block:
        cu ← cover[S\block]
        for c = 0..m-1:
            if cu 的第 c 位 and f[block] < ∞:
                res |= 1 << (c+1)
    cover[S] ← res
return cover[N-1] ≠ 0
```

**一般情形（机器不同）**。状态是「已用机器子集 U」的集合，用 `bitset over 2^m` 表示：

```text
cover[0] ← 1                     # bit 0 = 用空集可达
for S = 1..N-1:
    low ← S & −S;  i0 ← ctz(low)
    res ← 0
    for block ⊆ S with i0∈block:
        cu ← cover[S\block]
        for U ⊆ [m] with cu 的第 U 位:
            for k ∉ U:
                if k∈E_{i0} and f_k[block] < ∞:
                    res |= 1 << (U ∪ {k})
    cover[S] ← res
return cover[N-1] ≠ 0
```

状态数 `2^m`；对 m=3 是 8 位。`low` 固定「包含最低位任务的那一块」，消除块排列的重复。

**正确性直觉**：`cover[S]` 的每一位 U 表示「S 能被一个恰好使用 U 中机器的合法分配覆盖」。转移把包含 `i0` 的一块交给一台未使用的 k；由 `f_k[block]<∞` 保证这块在 k 上可行。所有划分都会被某个 block 枚举到，且 `low` 固定不丢解。

### 3.3 接进 PACE-ΠA 的搜索

```text
PACE-ΠA(σ,h):
  1  if R=∅: return YES([])
  2  if DEAD(σ): return NO
  3  σ←NORM(σ); A*←CANON(A); estt←est|R
  4  exact memo / F_sub / INT                            # v2.0，不变
  5  window 层: energy / clique / subset / HPACK          # v2.0，不变
  6  MINT / PACK-SET / SOP                                # v2.0，不变
  7  if ¬PACK(σ,h): F_pack.insert; return NO(PACK)        # v2.0，不变
  8  q ← tails(R)                                         # v2.0，不变
  9  if MAP-gate(σ):
         if |R| ≤ ncap:  ok ← MAP(σ)                      # 全 R
         else:           ok ← MAP(W), W = top_w(R)        # slicing
         if ¬ok: return NO(MAP)
 10  ready ← DHD(READY(R), R, p, est, q, h)               # tier 0.20
 11  K ← DCD(ready)                                       # tier 0.30
 12  for i in K:
         for k in machines(i):
             t ← max(A_k,est_i)
             if t+p_i+q_i(R\{i}) > h: continue
             r ← PACE-ΠA(child(i,k,t),h)
             if r=YES: return YES([(i,k,t)]+r)
 13  F_sub.insert(estt,A*); return NO(RESOLVE)
```

与 v2.0 的差异只有第 9 步；它在分支之前，只做有证书的剪枝。

### 3.4 证书格式与检查

**MAP-NO 证书**：

```text
kind = 'MAP'
payload = (rem, A, est, q, h, W)     # W=R 或见证
claim   = MAP(W) = 0
```

检查器独立重算：

```text
CHECK_MAP(inst, σ, W):
    recompute f_k[S] for k∈[m], S⊆W
    recompute cover[W] by the DP
    return cover[W] == 0
```

这是**重放证书**，不是短证书：检查代价与生成代价同阶（`O(3^{|W|})`）。它的优点是检查器不需要信任搜索树、不需要浮点、不需要 LP 求解器；缺点是证书长度是 `O(2^{|W|})` 的表（或直接重算）。

### 3.5 编译器优化

1. **profile compilation**：把「m 机交错」编译成「m 张单机 profile + 一次划分/分配」。这是强度削弱：从搜索树的 `d!` 变成根上的 `3^n`。
2. **CSE（孪生机器）**：按 `(A_k, E_k 列)` 给机器分类；同类只算一次 `f`。单类时 DP 从「机器子集」退化成「已用台数」。实测 n=16 根 0.3323→0.0893 s（3.72×）。
3. **dead-machine elimination**：`A_k>h` 或对 R 中所有任务都不 eligible 的机器删掉；`f_k[S]=∞` 的块跳过。
4. **slicing / partial evaluation**：n>16 用 `W=top_w(R)`；`MAP(W)=0` 直接剪，`MAP(W)=1` 退回 v2.0。planted n=17–24 上 21/21 命中。
5. **gate**：`slack0≤4` 且 `n≤16`；easy 与松状态不付 3^n。

### 3.6 复杂度

设 `k=|W|`、`d=|Ready|`、`c=|K|`。

```text
profile（每类机器）:     O(k 2^k) 时间，O(2^k) 空间
单类 DP:                 O(3^k · m) 时间，O(2^k) 空间
一般 DP:                 O(3^k · m · 2^m) 时间，O(2^k · 2^m / 64) 空间
MAP 每节点（k≤16）:      3^16 ≈ 4.3×10^7 次 block 枚举；C 内核约 0.03–0.09 s
见证（k=15）:            3^15 ≈ 1.4×10^7；约 0.01–0.03 s
主搜索:                  N(σ) = 1 + Σ_{i∈K} N(σ_i)，最坏仍指数
```

MAP 的代价是**每个被调用节点一次 3^k**，不是多项式；它把指数从搜索树搬到证书。`ncap=16` 是硬上限；n>16 只有 15 点见证，不声称完备的装填剪枝。

## 4. 定理与证明

### 4.1 单机 profile 正确性

见引理 1。核心：最后一个任务必是 sink；删去它后前缀仍是合法单机顺序；递推取 min。

### 4.2 MAP 可靠性

见引理 2 与定理 1。核心：可行排程按机器分块，每块的实际顺序给出 `f_k[S_k]≤h`，所以 MAP 是必要条件。

### 4.3 MAP 在孪生机器上退化为 β

见定理 2。核心：孪生机器可以接收任意块，块数 ≤m 即可单射到 m 台机器。

### 4.4 严格分离

见定理 3。两个分离例分别打「资格」和「可用时间」：β 只数块，MAP 还要求块能被不同机器接住。

### 4.5 见证可靠性

见引理 3 与推论 1。核心：把 R 的合法分配限制到 W，块变成子序列，仍可行；不同机器仍不同。

### 4.6 集成保持完备性

**定理 4（集成）**。PACE-ΠA 只可能比 v2.0 多剪「已证明 NO」的状态；未被剪的状态仍按 v2.0 的 DHD/DCD 分支。因此：

- 若 PACE-ΠA 返回 YES，排程可行；
- 若存在可行排程，PACE-ΠA 不会返回 NO（除非 MAP 不可靠，而定理 1 与推论 1 排除了这一点）。

**证明**。第 9 步的剪枝由定理 1（全 R）或推论 1（见证）给出 NO 证书；其余步骤逐字是 v2.0。对搜索树归纳：每个被剪子树确实无解；未被剪的分支覆盖 v2.0 的全部分支。∎

### 4.7 CSE 正确性

**定理 5（孪生机器 CSE）**。若机器 k,l 满足 `A_k=A_l`，且对所有 `i∈R` 有 `k∈E_i ⇔ l∈E_i`，则 `f_k[S]=f_l[S]` 对所有 `S⊆R`。

**证明**。递推只通过 `A_k`、`E_i` 的成员关系和 `S,est,p,q,h` 访问机器；这些在 k、l 上逐项相同，归纳即得。∎

### 4.8 只剪 NO，不剪 YES

**定理 6（单向性）**。`MAP=1` 时 PACE-ΠA 不做任何剪枝；`MAP=0` 时才把状态标 NO。因此 MAP 的假 YES（把不可行说成 unknown）只损失剪枝，不产生错误答案；MAP 的假 NO 才会破坏正确性，而定理 1/推论 1 排除了假 NO。

**证明**。看第 9 步：`if ¬ok: return NO`。`ok=1` 时控制流继续到 v2.0 的分支。∎

| 穷举 n=5，m=2，所有 DAG，p∈{1,2}，h 窗口 | **103,226** | **0 不一致**（102.23 s） |
| `h=OPT` 假 NO | 38+deep+held-out+对抗+planted | **0 次** |
| 返回排程独立验证 | 所有 YES | 0 违规 |

「0 不一致」的含义：同一引擎、同一 h、同一配置下，`map_on` 开与关返回同一布尔值；YES 时两边都独立验证排程（任务一次、优先、机器不重叠、资格、h）。穷举覆盖 n≤5 的所有 DAG；n=5 的 h 窗口取 maxh=3。MAP-vs-暴力直接测「MAP=0 是否可能假 NO」：3,000 个随机状态中 0 次。仍不是形式化验证。

## 6. 负结果与陷阱

### 6.1 MAP 是松弛，不是判决

5 个 held-out 残例（31/26/47/78/130 → 26/23/47/42/46）都是 `MAP=1` 但不可行。它们的不可行性来自**跨块优先序**：i 在块 A、j 在块 B、i≺j，MAP 把两块当成可以独立安排，丢掉了这个时间耦合。这是 MAP 的定义决定的，不是实现 bug。

### 6.2 β 只数块，不数机器

large_het#1 是真实分离：β=3，MAP=0。任何「只数块」的证书在异资格/异可用时间上都会漏掉这一类。反过来，MAP 在孪生机器上严格退化为 β，所以它不是「另一个启发式」，而是 β 的机器匹配加强。

### 6.3 没有短证书

MAP 的 NO 需要检查器重跑 `3^k` 的 DP；它没有 LP 对偶那样的 O(n) 短证书。CBC/团证书是短的，但在 hard3#5 和 deep 上全部不命中（ω≤3 而 β=4）。本轮选择「可重放」而不是「短」；这是明确的取舍。

### 6.4 见证是启发式

n>16 只跑 15 点密度见证。若硬核不在前 15，MAP 不剪，退回 v2.0。planted 的 21/21 命中不能推广到自然 n>16；需要更多自然紧实例才能评估见证选择。

### 6.5 时间不是免费的

38 3.61×、deep 4.07×、held-out 4.27×；easy 1.028×。对根下界已经接近 OPT 的实例，MAP 是纯开销；`map_tau` 门就是为此存在的。若只看时间，v2.0 仍更快；v2.1 用时间换节点/证明。

### 6.6 `omd` 是继承来的硬门

v1.6 的非延迟机器支配 `omd` 只在全资格时成立；异资格实例必须 `omd=False`。本轮实验里，38 例的 v2.0 基线用 `omd=fe(inst)`（全资格才开），large_het 用 `omd=False`；否则 v2.0 自己就会假剪，MAP 的对比没有意义。MAP 本身不依赖 `omd`。

### 6.7 一个差点发货的 DP bug

最初 `cover[S]` 用「机器集合的并」当状态：`{0}` 和 `{1}` 的并记成 `{0,1}`，于是 hard3#3 在 `h=OPT` 上被假 NO。正确状态是「机器子集的**集合**」（bitset over `2^m`），不是并。这个 bug 在 38 例的 `h=OPT` 断言上立即暴露；如果只测 `h=OPT−1`，它会被 38/38 的「正确」掩盖。教训：**证书核的 DP 必须用 h=OPT 的 YES 断言和独立暴力对拍，而不是只测 NO**。

### 6.8 最坏复杂度没变

MAP 每节点 `3^k`，`k≤16`；搜索树最坏仍是 `d!`。它把指数从搜索树搬到根上的证书，不改变 `P|prec|Cmax` 的 NP-hard 性。同步层 + 未来两两不可比 + p 两两不同时，MAP 仍可能 `MAP=1`，分支因子回到 d。

### 6.9 没有形式化验证

1,500 随机 + 103,226 穷举 + 3,000 MAP 暴力 + 独立 YES 验证是很强的证据，但不是 Coq/Lean；定理 1–6、引理 1–3 是纸面证明 + 可重放内核。

### 6.10 内存

`cover` 按 `2^22` 个 `uint64` 分配（32 MB），每个机器类 `f` 按 `2^22` 个 int 分配（16 MB）。m=3 约 80 MB；ncap=16 时实际只用 `2^16`，但分配按上限。若要多线程/多实例，需要改成按 N 分配或池化。

### 6.11 公共期限

MAP 用公共期限 `h` 与 `q_i`。若任务有各自期限 `d_i`，把 `h−q_i` 换成 `d_i`，引理 1/2 仍成立；但引擎里没有这条路径，需重证并重测。

## 8. 已知风险

1. **松弛边界**：MAP 忽略块与块之间的时间耦合；5 个 held-out 残例是这条边界的直接证据。任何「MAP 能闭所有紧实例」的说法都是错的。
2. **最坏复杂度没变**：每节点 `3^k`，搜索树仍指数；同步层 + 无装填矛盾时 MAP 不剪。
3. **n>16 的见证是启发式**：只跑 15 点密度见证；硬核不在前 15 就退回 v2.0。planted 的 21/21 不能推广到自然实例。
4. **没有短证书**：MAP-NO 是重放，不是 O(n) 证明；检查器要重跑 3^k。
5. **时间**：38 3.61×、deep 4.07×、held-out 4.27×；对根下界接近 OPT 的实例是纯开销。
6. **`omd` 硬门**：异资格实例必须 `omd=False`；这是 v1.6 继承的规格，不是 MAP 的可调参数。
7. **`est/q/A` 必须精确**：`est` 高估、`q` 高估、`A` 高估都会让 MAP 假 NO；低估只会让 MAP 更弱（更安全）。PACE 里 `est` 是精确最长头、`q` 是精确最长尾、`A` 是实际可用时刻。
8. **CSE 的等价条件**：只有 `A_k` 相同且资格列逐项相同才能共享 profile；不要把「资格集大小相同」当成孪生。
9. **DP 状态必须是机器子集的集合**：用并集会假 NO；本轮已修，但这是容易复发的 bug 类。
10. **frontier 截断/`nodecap` 破坏严格单调**：`F_sub` 的 K=48 截断和 nodecap 可能让个别实例节点数不严格单调；本轮未观察到损失，但定理之外不保证。
11. **没有形式化验证**：纸面证明 + 随机/穷举/暴力，不是 Coq/Lean。
12. **公共期限**：各自期限 `d_i` 的路径未实现；需把 `h−q_i` 换成 `d_i` 并重证。
13. **门的覆盖率**：`slack0≤4` 是启发式；更松的紧实例可能不触发。门关掉只少剪，不多剪，但会改变实验数字。
14. **内存**：按 `2^22` 分配，m=3 约 80 MB；多线程/多实例需要池化或按 N 分配。
15. **`MAP=1` 不是可行性证明**：它只是「未知」；不要把 MAP 的 YES 当成排程或上界。

---

## 9. 一句话最大风险

**MAP 把「数块」升级成「块到机器的匹配」，但它仍然忽略块与块之间的时间耦合：当不可行性来自跨块优先序而不是装填/资格时，MAP 只能说 YES，搜索仍要回到 d!；5 个 held-out 残例就是这条边界。**
