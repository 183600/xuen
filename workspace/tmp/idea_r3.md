## 一、这一轮我不再问「割够不够强」

v7.1 的数字摆在那里：141 例 NO，QNC 147 LP / 137 节点，其中 139 例根层就闭合（135 例 ≤1 LP）；quorum 只在 2 例触发；clause 剪枝 0 命中。上一轮我把这解释成「数据分布把收益压住了」，这当然对，但它不是一个可执行的方向。

真正让我停下来的是另一个观察：

> v7.1 的 E 全部是在 LP 已经不可行的节点上「捡」到的。

叶子不可行，所以有 Farkas 证书；证书里再读出 E。也就是说，**证书是失败的副产品**。可是那些根层可行的实例，LP 本身是一个很好的 oracle：它知道每个任务的时间质量压在哪里。我们为什么不能在 LP 还活着的时候，主动问它一个反事实的问题？

  「如果我把这个 start 禁掉，你还可行吗？」

如果不可行，那么这一禁就逼出了一张证书：**这个 start 是被迫的**。这不是「割更强」，这是「证书的产地」变了。v7.1 问的是「证书能证明多大的区域」；本轮问的是「证书能不能在没失败的时候被制造出来」。

## 二、三个灵感词各自落在哪

- **local search**：把「禁一个 start」看成一步 move。状态是域限制，move 只缩小域；如果 move 后 LP 不可行，这一步不是失败，而是一张 unit core 证书。
- **derandomization**：最自然的探测是随机的——按 LP 的分数解 z 抽一个 start。但随机不可复现，而且会反复抽到同一个任务的同一个 atom。用条件期望把它去随机化：先抽概率最大的 job，再抽质量最大的两个 atom。
- **deterministic algorithm**：排序键固定、tie-break 固定、Farkas 舍入网格固定、审计用整数重放。没有 RNG。

## 三、第一次尝试：随机探测，以及它为什么不够

我在纸上先写了随机探测 R：

1. 解根 LP，得到分数解 z；
2. 以 z_i 为分布抽一个 start t，禁掉 c=(i,t)，再解一次 LP；
3. 若不可行，得到 unit core「s_i=t」；再抽第二个 t'；
4. 若同一任务的两个不同 start 都被迫，则 NO；
5. 否则重采样。

这个算法在 idx 5/47 上会成功，因为这两个实例的分数支撑里，确实有整个任务的分数质量都落在「被迫」的 atom 上。但它有三个毛病：

- 不可复现，实验结果没法逐位重放；
- 采样会反复落在同一个 job 的非被迫 atom 上，浪费 LP；
- 「抽哪个 job」没有用到割的信息，而真正紧的信息恰恰在割里。

于是我做了这一步替换：

> 随机抽 job  →  按「紧割关联度」排序 job  
> 随机抽 atom →  按「LP 质量」排序 atom

这不是拍脑袋。把「随机探测」写成一个分布 π：job 以正比于紧割度 d_i 的概率被选，atom 以正比于 z_{i,t} 的概率被选。条件期望（MoCE）的贪心版本就是：取 π 的众数 job，取该 job 质量最大的两个 atom。**去随机化在这里不是「去掉随机」，而是「把随机探测的众数变成一个可排序的确定性对象」。**

## 四、形式化：unit core 与 pair refutation

设 D 是全列集，C 是已分离的 SD 割集，B⊆D 是当前允许的列。P(C,B) 是带这些割和这些列的 start-time LP。

对 c=(i,t)，做一次 **probe**：

  P(C, B∖{c}) 是否可行？

如果不可行，称 c 是一个 **unit core**，并记一条 **unit clause** κ(i,t)。它的意思是：

> 每个满足 B 的可行调度都有 s_i = t。

证明是一行：若某个可行调度 s 满足 B 且 s_i≠t，则 s 的 z 只用 B∖{c} 的列，于是它是 P(C,B∖{c}) 的可行点，矛盾。

如果同一个任务 i 上有两个不同的 unit core，κ(i,t1) 和 κ(i,t2)，t1≠t2，那么任何可行调度既要 s_i=t1 又要 s_i=t2，矛盾。这就是 **pair refutation**。

这里有一个我必须写下来的 soundness 边界：**probe 只能在根层做**。在分支节点，B 里含有分支禁掉的列；此时「P(C,B∖{c}) 不可行」只说明「在这个分支里 s_i=t」，不能提升成全局 clause。v7.1 的 E 之所以能全局化，是因为它的证书在 E 之外的所有列上重放通过；probe 没有这个 lifting。把非根 probe 的 unit clause 塞进全局 force，会把「分支内被迫」误当成「全局被迫」。这是方向错误的一个新版本，和上一轮把 E 当成 ban 是同一类错误的近亲。

根层为什么可以？因为根层的 B 只含全局 force（force 本身来自根层 unit clause 或 v7.1 的 quorum），不含任何分支限制。所以根层 probe 得到的 κ 是全局有效的。

## 五、算法 UCP-ALC

状态从 v7.1 的 (C,Q,force,L,B) 再扩一点：

  S = (C, Q, force, L, B, Π)

- C：SD 割集，只增；
- Q：clause 集，只增；
- force：全局强制域，只缩；
- L：已认证叶子；
- B：LP 预算计数；
- Π：probe 计数（probes、portfolio、pair witness）。

主循环：

1. 零 LP 前检：某个 D_i=∅ → NO。
2. 解 lazy SD LP（按需分离割）。
3. 不可行 → 走 v7.1 的 quorum 学习；可行且整数 → YES；可行但分数 → 进入 probe。
4. **根层 probe**：
   - 只看分数 atom（0<mass<1）；
   - 只取分数 atom 数恰好为 2 的 job（这样两次 probe 覆盖整个分数支撑）；
   - 按紧割度 d_i 降序、再按 job id 升序；
   - 取该 job 质量最大的两个 atom，依次禁掉再解 LP；
   - 两个都不可行 → pair refutation，直接 NO；
   - 第一个可行 → gate 关闭，整个 probe 阶段放弃（只花 1 LP）；
   - 一个不可行、一个可行 → 记下这个 unit core，但默认**不 force**，回退到 v7.1 的 median DFS。
5. 回退 DFS 与 v7.1 完全一致；probe 不改变割集，也不改变搜索路径。

关键工程选择是 **pair-only + gate**。我一开始实现了「单 unit core 就 force，然后继续 probe」的完整局部搜索版本；它在 7 个分支例上没有更好，却在扰动例 holdout36 上把 16 LP 变成 18 LP：force 是可靠的，但它改变了搜索路径，路径变差就会吃掉 probe 的收益。pair-only 版本只在「已经能证明 NO」时改变结果，否则原样回退，所以它的最坏代价被 gate 限制在 1-2 个 LP。

**YES 侧小测**：13 个 h=OPT 的 holdout 例，UCP 全部返回 YES，0 个误判 NO；probe 开销 0 或 1 LP。

**负结果**

- 完整 force 版本在 holdout36 的扰动例上 18 LP，pair-only 17 LP，QNC 16 LP；可靠不等于不退化。
- 另一个扰动例 holdout5-p0 用 pair 在根层闭合，6 LP / 1 节点，和 QNC 的 6 LP 持平，但节点 3→1；所以「根层闭合」不总是省 LP。
- 我只多造出 2 个可用的压力例（改 p 后重算 OPT），样本很小；这两例不能支撑统计结论。
- 主数据集 139/141 根层就闭合，UCP 的 2 LP 收益会被任何平均值淹没；本轮真正的证据是 7 例分支子集的 80% 节点下降。

## 七、这一轮学到的东西

1. **证书可以从 feasible LP 里「反事实」地制造**。不必等 LP 失败；禁一个 start，问它是否还可行，失败就是证书。
2. **最有用的对象不是更大的割，而是一对 unit clause**。两张单列证书 + 一条逻辑规则，比一棵 DFS 树短得多。
3. **去随机化在这里是一个排序问题**。随机探测的众数版本需要一个「紧度」信号；SD 割的关联度恰好是这个信号，而且比 job id / LP 质量强得多。
4. **根层不是工程限制，是 soundness 边界**。非根 probe 的 unit clause 只在分支内成立；把它全局化，就是把「分支内被迫」当成「全局被迫」。
5. **主数据集已经饱和**。141 例的平均 LP 几乎不动；真正的收益在「需要分支」的 7 例上，而这 7 例只来自两个家族。不要用 141 例的平均值掩盖 7 例的 80%，也不要用 7 例的 80% 冒充 141 例的结论。

## 八、一句话最大风险

**紧割度排序的 7/7 精度只来自 7 个实例、两个家族；如果它只是这套 SD 割生成器的相关性而不是可迁移的瓶颈信号，换到别的分布上 root probe 会花 1–2 个 LP 却找不到 pair，本轮的全部收益就归零。**
