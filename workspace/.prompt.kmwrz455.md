## 1. 研究者直觉（先直觉与动机，后形式化）

**直觉 1（热管理 → 「官方接口旋钮本身就是热旋钮」）**。读完 F60 我最强烈的反应是：**这套接口把计算负载的控制权几乎全交给了选手**。传哪些相机（`obs_delta_indices` 的键）、什么分辨率（`image_resize`）、一次推理管几步（`action_chunk_size`）、joint 还是 ee 空间——四个旋钮每一个都同时改变「传输字节数、GPU 计算量、每步调用频率」。这正是热管理的第一类抓手，而且不需要任何魔改：把 `T_a` 从 8 调到 16，单 episode 的推理次数减半、GPU 热积累速率减半、每步时延的方差也下降（更少次调度抖动）；干扰场景再把 `T_a` 调小保反应速度。第二类抓手在机器侧：G1 页（F62 旁证，unitree.com/g1，2026-11-10）写明关节电机为「低惯量高速内转子 PMSM（更好响应与散热）」、整机「局部风冷」、可选 Orin 高算力模组、臂限载约 2–3kg——**长时程高频操作下电机热积累会触发限扭，直接表现为抓不稳、放不准**（F63 已验证此机制在腿式上的存在性）。第三类抓手在最关键处：官方**记录每步时延与变异性并作为可信度依据**（F60）——热节流导致的时延抖动不是体验问题，是**写进成绩单的评分风险**。所以热管理在本赛道的准确定位是：**把「热账本」作为与成功率和步骤分并列的第三本账来管**。

**直觉 2（任务规划 → 「步骤分是排名的一半，不是边角料」）**。F59 明示排序同时看平均成功率与步骤分。v16 的 IP-47 任务代数只保证「语义正确+类型安全+证书兼容」，对**用了多少步**完全无感；而失败重试、来回纠偏、无谓的 retreat、把简单任务规划成复杂技能序列，全部直接吃步骤分。更微妙的是语言指令**全 episode 不变且无时间轴**（F60）——这意味着规划是「一 episode 一次主规划 + 失败驱动重规划」的结构，重规划的质量与频率（尤其 5 类泛化场景中的人为干扰）决定步数浪费。GAVEL（F64）给出了正确的规划形态：**先在可预测的图世界模型里推演后果、检测违规、能直接修就直接修，LLM 只留给需要语义推理的少数场合**——这同时省步数（少失败）和省时延/热（少调用大模型）。我把它扩展为「期望得分规划」：每个候选计划估计 E[得分] = Π p_s(技能|场景) × g(步数) − 风险惩罚，其中 p_s 先验从自采/开源数据统计得到，失败后写入失败记忆库（同一物体×同一技能失败→升级策略而不是重试）。

**直觉 3（轨迹优化 → 「VLA 的最后一毫米交给 TO」）**。「榜首不到 30%」（F66 假说）的失败谱系里，我敢押最大的一块是**末端执行精度**：VLA/流匹配策略在「大致到位」上已经很好，但放置公差、双臂交接、插入类任务的最后 5mm 是学习策略的系统性短板（RobustVLA/DRIFT 提示其表征对扰动敏感）。而 TO（iLQG/DDP 类，配学习残差动力学）恰好补这一块，且额外白送三样东西：(a) **约束**——关节限位、自碰撞（URDF）、干扰物包络（语义图直接给椭圆体/网格包络），这在「干扰物」泛化场景里是刚需；(b) **能量项**——力矩加权最优天然降低电机热积累（直连直觉 1 的机器侧）；(c) **时间项**——更快更短的运动=更少步（直连直觉 2 的步骤分）。但必须诚实面对一个接口事实：我们输出的是**目标（joint/ee），不是力矩**（F60），机器人内部控制环未知——所以真 TO 不是「力矩层 TO」，而是**参考轨迹优化 + 跟踪误差模型**（跟随机理需要 E38 辨识实验）。落地形态锁定为「VLA 热身 + TO 精修 + CBF 兜底」：流式策略出终端 seed 和前几步，TO 在其上精修，步级 L0 守护不变。这与 Aero-VPA/PRISM 的「少步精修」思潮同向，但我们是轨迹层而非策略层。

**直觉 4（三词咬合：TO 是三角的中心）**。单独看三件事都只是优化；串起来才是架构：TO 的能量项压低热积累 → 热预算 governor 可以把省下的算力让给「大模型重规划/高分辨率感知」；步数感知规划决定何时值得付 TO 的计算成本（放置类才精修，转移类用流式）；热状态又反过来约束规划频率与 TO 迭代次数。三者共享同一本账——**Δ 资源平面（热/时延/步数三账本）**，v16 四层全部挂到这本账上被调度。

**直觉 5（修剪即深化：v16 最大的敌人是它自己）**。v16 结尾自述最大风险是「服务化/证书化/代数化的组合爆炸」。本轮联网时我逐条对照官方接口现实，发现 v16 中至少四项是**能力展示型而非得分型**设计：(a) IP-45 的舱壁/多租户隔离——官方并发上限就是 N 个端口（F60），租户级资源配额纯属过度设计还引入时延风险；(b) IP-46 的 μ 分析全形式证书——非线性系统上 D-K 迭代必然过度保守，v16 的 E62 其实已自认；(c) IP-47 的并行组合算子 ⊗——32 项桌面任务以序列为主，双手协调应作为**复合技能句柄**交给 IP-50 的双臂 TO，而不是让规划器做并行代数；(d) IP-47/IP-44 的 MAML 元预训练——数据与算力门槛最高、边际得分最低，用检索式适配（RARA，F65）作 P0 轻替代。**本轮把四项降级 P2，是「深化」而不是「砍」——清单的总得分效率因此上升。**

## 3. 形式化直觉（严格版见产物区 §3）

**定义 25（Δ 资源平面：三账本）**：`Ledger = {H_gpu(t), H_motor(t), S_used(t), L_p99(t)}`，其中 H_gpu 为推理服务器 GPU 温度/占用（nvidia-smi/pynvml 遥测）、H_motor 为电机热代理 `Ĥ=∫ τ̂ᵀτ̂ dt`（τ̂ 由目标轨迹经逆动力学+URDF 估计，A37）、S_used 为已用步数（chunk 计数）、L_p99 为热态时延分位。**决策原则**：任一账本越界→触发 IP-48 降额，而非硬性中止（保成功率优先）。

**定义 26（官方接口旋钮作为资源算子）**：`K = {obs_keys ⊆ K_obs, resize: K_img→[h,w], T_a ∈ ℕ⁺, control_space ∈ {joint, ee}, prosody_mode, model_branch}`，每个取值向量对应三元组 `(compute_cost, thermal_rate, reactivity)`。IP-48  governor 即在该旋钮空间上按账本状态做约束优化：`max reactivity s.t. thermal_rate·T_remaining ≤ H_budget ∧ L_p99(T_a) ≤ SLA`。

**定义 27（期望得分规划）**：候选计划 π（技能 DAG）的期望得分 `E_score(π)=Π_{s∈π} p_s(s|scenario)·g(N_steps(π))−λ·P(fail|π)`，其中 `g` 为步骤分的单调减函数（公式未公开，A34：按 1/N 与分段两种口径做鲁棒优化），P(fail) 由图世界模型推演 + 失败记忆估计。**重规划触发**：IP-24/28v2 失败信号 ∨ 证书违约 ∨ governor 进入 CRITICAL。

**定义 28（参考轨迹 TO）**：`min_u ∫(τ̂(u)ᵀ R τ̂(u))dt + γ·T + ρ·terminal_precision_error`，约束为关节/自碰撞/物体包络/夹爪时间窗/pivot 准静态，动力学用「目标跟踪闭环模型」`ẋ=f_track(x, u_cmd)`（辨识自 E38）。热启动 = VLA chunk 头 + 上解时移。**关键定位**：TO 精修的是参考（official action 就是参考），安全由 CBF（IP-33）与收缩证书（IP-46）兜底，因此 TO 解不必最优也不必保证——它只需比 VLA 直出更准且可快速验证（MuJoCo 门）。

## 4. 关键决断

1. **账本化**：热/时延/步数升格为 Δ 资源平面，所有层被其调度；v16 的证书、合约、服务总线全部成为账本的「被观测对象」。
2. **接口即工程**：把官方四个旋钮（obs/resize/chunk/space）当作一等设计对象写进 governor——这是本赛道独有的、零接口改造成本的创新空间。
3. **TO 补精度**：不做 TO 替代学习，做「学习热身+TO 精修+守护兜底」三段式；TO 目标是参考而非力矩（诚实于接口）。
4. **规划看分**：E_score 目标把成功率与步骤分统一进一个期望，步数从副产物变成优化变量。
5. **修剪四项**：舱壁、μ 分析、⊗、MAML 降 P2——兑换复杂度预算给三条新线。

## 5. 本轮最大风险（一句话）

### 3.2 IP-48 THERMAL-BUDGET-GOVERNOR（热预算治理，完整设计）

**IP 卡片（六字段）**：
- **动机**：F60 §5–6 证明并发推理（N 端口同时调用+共享后端）与「每步时延平滑性/动作统计规律性=可信度」并存；F62 证明 G1 电机热是长时程物理约束（PMSM 散热+风冷+臂限载 2–3kg）；F63 证明热状态作为控制输入在腿式上有效。榜单/可信度都把「稳定交付」计分。

**算法（状态机）**：
```

每控制周期(1s)：
  若 H_gpu≥θ_gpu 或 L_ewma>SLA_hot：State ← CONSERVATIVE
      动作：T_a 档+（下设两档预设，按 episode 类型预选）、image_resize 降一档、
            obs_keys 去腕部(仅高位)、prosody→平滑、共享后端关掉低优攒批
  若 Ĥ_motor≥θ_motor：State ← CRITICAL
      动作：轻模型分支、暂停 IP-49 大模型重规划(改用图世界模型直接修)、TO 迭代次数上限 3
  若 State≠NOMINAL 且 H_gpu<θ_gpu-回差 且 L_ewma<SLA_hot·0.8：State ← RECOVERY
      动作：逐档恢复(先 resize 后 T_a 后分支)，每步恢复间隔≥60s(防抖)
  若越界持续>3min 或恢复失败：通知 IP-46 吊销热稳态 SLO 证书+IP-38 降额档
```
**正确性论证**：P42（时延方差单调性）——在算力饱和区，单位时间推理事件数(∝1/T_a)与时延方差正相关（排队论 M/G/1：到达率 λ 服务率 μ 的差越大，等待时间方差越大）；T_a↑⇒λ↓⇒Var(L)↓⇒可信度指标改善。P43（热-力矩单调性）——PMSM 温升率∝i²R≈k·τ²（F62/F63），平滑 prosody 与 TO 能量项使 ‖τ‖↓⇒温升率↓⇒限扭概率↓⇒成功率漂移↓。P44（准入不饿死）——截止期调度（EDF）下，每个 get_action 在其 chunk 窗口内完成，吞没=违反窗口才会劣化轨迹，而非时延。

**已知风险**：旋钮半静态化（T_a/resize  locked 于 metadata）——缓解：为不同干扰等级预设 2–3 套 metadata 档位，由赛前场景画像选择；遥测缺失环境（评测机无 nvidia-smi 权限）——缓解：以 L_ewma 为间接热指标（时延本币即热的影子价格）。

### 3.3 IP-49 STEP-SCORE-PLANNER（步数得分规划，完整设计）

**IP 卡片（六字段）**：
- **动机**：F59 明示排序=平均成功率+步骤分；F60 明示语言指令全 episode 不变→「一次主规划+失败驱动重规划」结构；F66 假说下失败主要来自泛化场景与精度——重规划质量直接决定步数浪费。
- **与现有方案差异**：SayCan 式（R136）与 IP-47 只优化语义可行性；GAVEL（F64）优化「可靠+省 LLM」但不显式优化步数分。我们把**步数成本 + 每技能成功率先验 + 场景画像 + 失败记忆**统一进 E_score 期望；并把步数作为一等状态量与 IP-48 账本联动。
- **技术可行性**：技能集≤O(100)、候选计划经图世界模型剪枝后 beam≤16，单次规划 <50ms；LLM 仅在语义缺边时触发（GAVEL 同构）。
- **所需资源**：数据=p_s 先验表（自采/开源初始化，按 5 场景分桶）、失败记忆库、图世界模型（IP-36 关系库+前提升）；算力=本地小 LLM（SLoSa 2610.28955 证明低功耗可胜任，顺带省时延省热）；接口=reset()/language 提供 episode 边界与指令。
- **落地步骤**：① 建 p_s 先验（E70 随测随更新）；② 图世界模型最小版（物体位置信念+动作前置/效果）；③ beam 搜索+E_score；④ 失败记忆与策略升级；⑤ 场景化策略开关；⑥ E70 验收。
- **风险**：步骤分公式未公开（A34）→以两种口径（1/N、分段）做鲁棒（取 min）；p_s 分布外失效→贝叶斯平滑+在线更新；图世界模型维护成本→只用粗粒度关系，精细状态交 IP-50/MuJoCo。

**符号表**：S=技能集；p_s(s|σ)=场景 σ 下技能 s 成功率先验；g(N)=步骤分函数；W=(Obj, Rel, pre/eff, Belief)=图世界模型（F64）；M_f={(obj, s, fail_sig)→升级策略}；λ=风险厌恶系数。

**算法**：
```
输入：指令 l（静态）、观测 o、账本 State、场景画像 σ
1. 主规划（reset 后一次）：
   G = (V,E) ← LLM/W 联合解析 l（W 能推的边不调 LLM——GAVEL 原则）
   beam search over V：f(n)= −E_score(π_n), h(n)=W 中名义最短步数(可采纳启发)
     E_score(π)=Π_{s∈π} p_s(s|σ) · g(N_π) − λ·P(fail|π)
     P(fail|π)=1−Π(1−q_s)，q_s 由 M_f 中同类失败率上调
   输出 Plan=[(skill, cert_req, budget_req, prosody_hint)]
2. 执行中：IP-24/28v2 失败信号或证书违约 → 软重规划
   - 查询 M_f(obj,s,fail_sig) → 命中：升级策略（换抓取点/推-抓/双手/换工具）而非原地重试
   - W 预测-检测-修复：若违规可由 W 直接推演修正(物体被移走/不再满足前置)，就地修；
     仅当需要语义推理（目标重指涉）才调 LLM 重规划
   - 重规划期间当前 chunk 继续执行到安全停止点（边执行边规划，省步）
3. 场景化策略（σ 来自 5 泛化轴）：
   - 干扰物：TO 避障约束开启(IP-50)；可选预推(distractor)仅当 p_s 增益>步数代价
   - 未见物品：IP-30 多假设候选→多假设 beam（按 p_VLM 前 3 名分叉，提交后即消去）
   - 人为干扰：软重规划+chunk 安全截断；不熔断整 episode
   - 位置/背景：规划不变，仅感知重锚定（省步）
```
**复杂度**：beam≤16、启发式 admissible ⇒ O(|V|·beam·branch)；W 查询 O(log)；LLM 调用率 <10%/episode（E70 实测）；总规划时延 <50ms（热态亦 <150ms，不吃 SLO）。

**正确性论证**：P45（期望得分一致性）——g(N) 单调减，p_s·g 对 p_s 单调增，故 beam 保留高 E_score 计划不劣于随机重试；P46（不重复失败）——M_f 命中后策略升级，P(同类失败再次发生) ≤ q_prior·(1−Δ_q)；P47（软重规划步数非增）——边执行边规划使重规划开销摊销在已执行安全步内，E[N_steps] 不高于「停-等-规划」。

### 3.4 IP-50 HYBRID-LEARNED-TO（学习-TO 混合轨迹，完整设计）

**IP 卡片（六字段）**：
- **动机**：<30% 瓶颈的假说性主因是末端执行精度（放置公差/双臂交接/插入）；VLA 表征对扰动敏感（RobustVLA/DRIFT）；官方动作空间=目标（joint/ee）+chunk 顺序执行（F60）→ 优化「参考轨迹」完全契合接口；TO 白送约束（关节/自碰撞/干扰物包络）、能量（降温升）、时间（少步）。
- **与现有方案差异**：不是 TO 替代学习（伺服/规划派），也不是纯 VLA（端到端派），而是**三段式：VLA 热启动→TO 参考精修→CBF 兜底**；与 Aero-VPA/PRISM 的「少步精修」同向但落在轨迹层；与 F63 残差策略差一层级（它是策略层热条件，我们是轨迹层能量-时间-精度多目标+接口级目标输出）。
- **技术可行性**：G1 桌面包络内任务空间 14 DoF（双臂）+pivot 准静态，问题规模小；iLQR 配热启动迭代 3–8 次即可，CPU 毫秒–十毫秒级；CQDC-Warp（2610.21349）证明可微准动力学仿真可 GPU 化备援。
- **所需资源**：数据=E38 跟踪模型辨识（目标→实际运动残差，~30min 自采）；URDF+MuJoCo 模型（A17 未决：缺失时退化=跳过自碰撞门+关节软限位）；算力=iLQR 单次 <10ms CPU；接口=官方 joint/ee 目标通道+chunk。
- **落地步骤**：① E38 辨识跟踪模型；② 仿真搭 TO（MuJoCo）；③ E71 放置/插入精度专项（VLA vs VLA+TO）；④ 真机接入 IP-43 流式（chunk 头热启动）；⑤ MuJoCo 门上线；⑥ E72 端到端验收。
- **风险**：URDF 缺失/失准→自碰撞门失效（退化保守限位+小增益 Replay）；跟踪模型 OOD→TO 解过激进（线搜索+收缩证书监控兜底）；TO 超时→降级 VLA 伺服（硬约束 deadline=chunk 窗口 50%）。

**符号表**：x=(q_arm(14),q_pivot)；u=目标序列（joint 或 ee 6D）；f_track=学习跟踪闭环模型（E38）；𝒪=物体包络（IP-36）；R,J̄=关节/末端约束；T=段时长；w_E,w_T,w_P=能量/时间/精度权重。

**算法**：
```
输入：waypoints(IP-39)、VLA chunk 头 a^VLA_{0:k}、当前状态、包络 𝒪、prosody 模式
1. 热启动：init = a^VLA 前 k 步 + 上解得当解时移(IP-43 流式先验)
2. 任务：min_u ∫ τ̂(u)ᵀR τ̂(u)dt + w_T·T + w_P·‖x(T)−x_goal‖²_W
   s.t. ẋ=f_track(x,u)；关节限位；自碰撞(URDF)；d(x, 𝒪)≥margin(按干扰物场景置 0/正)；
        夹爪时间窗[开/闭区间]；pivot 准静态(‖q̈_pivot‖≤ε)
   —— τ̂ 由 ID(q̂, q̂̇, q̂̈)+f_track 输出估计（参考层 TO，非力矩层，诚实于接口）
3. 求解：iLQR/DDP+line search；deadline=0.5·chunk 窗口，超时→VLA 伺服输出(硬降级)
4. 校验：MuJoCo(IP-35) 过一遍（自碰撞/可达/奇异）→ 不过则收缩增益重解或丢弃
5. 输出：T_a 步目标序列（官方 joint/ee 键）；IP-33 CBF 步级否决仍在最低优先级
6. 权重调度：放置/插入类 w_P↑（精度优先）；转移类 w_T↑；高热态 w_E↑（喂 IP-48）
```
**复杂度**：状态≤21 维、控制≤20 维；iLQR 每次 rollout+backward O(N_steps·d²)≈毫秒级；总热启动下 <10ms/次，非每步调用（waypoint 段切换或干扰触发时才解）。

**正确性论证**：P48（精度增益）——f_track 误差有界（E38 辨识残差 ε_id）时，TO 终端误差 ≤ w_P 决定的次优 + ε_id 传播项，相比 VLA 直出的末端方差 σ_VLA，E71 门槛要求 σ_TO≤σ_VLA/2；P49（约束保持）—— MuJoCo 门+URDF 限位+IP-33 CBF 三层并联，任一失效仍有下一层；P50（实时性）——deadline 硬截断+线搜索保证最坏情况下退化为 VLA，不恶化基线成功率。

# ===== 离线：跟踪模型辨识（E38，IP-50 依赖）=====
def identify_tracking_model(robot_if):
    traj = collect_excitation_traj(minutes=30)          # 目标-实际运动对
    f_track = fit_residual_dynamics(URDF_planar, traj)  # ID+残差网络

def build_priors(data):
    p_s = bayesian_smoothed_success_rate(data, dims=[skill, scenario])  # 5 场景分桶
    W = build_graph_world_model(data)   # 物体关系 + 动作前置/效果 + 位置信念(F64)
    M_f = FailureMemory()
    return p_s, W, M_f

# ===== 运行期：Δ-Plane governor + 主循环（IP-48/49/50）=====
def act_v17(obs, state):
    # 1. 账本更新（1Hz + 每步轻量项）
    ledger = update_ledger(H_gpu=telemetry(), H_motor=motor_heat_proxy(q_cmd_hist),
                           S_used=state.steps, L=L_ewma)
    knobs = governor(ledger)             # State∈{NOMINAL,CONSERVATIVE,CRITICAL,RECOVERY}
                                        # → T_a_eff, resize_tier, obs_keys_eff,
                                        #   prosody_mode, branch, admit_batch
    # 2. 主规划（reset 后一次）或软重规划（失败/证书违约/governor CRITICAL 且语义缺边）
    if state.need_plan:
        plan = step_efficient_planner(obs.language, semantic_map, p_s, W, M_f,
                                      scenario=state.sigma, budget=knobs)
        state.plan = plan
    # 3. 中层 → TO 任务（段切换/干扰触发时）
    if state.need_refine:
        task = midlevel(state.waypoints, obs, budget=knobs, certify=state.cert_req)
        # 4. IP-50：VLA 热启动 + TO 精修（deadline 硬截断）
        warm = stream_policy_head(state.plan.skill, obs)        # IP-43 流式头 k 步

                            f_track=state.f_track, W=(w_E, knobs.hot, w_P))
        if refined is None:                                     # 超时/MuJoCo 门失败
            refined = warm                                     # 降级：VLA 伺服
        state.traj = refined
    # 5. 步级执行 + 兜底（官方 action chunk 语义）
    chunk = state.traj.next_chunk(T_a_eff)
    if not guard.cbf_check(chunk):                              # IP-33
        chunk = resample_or_fallback(state, r=2)
    q_cmd = adapt(chunk, control_space=state.control_space)
    # 6. 失败监测 → 软重规划 + 失败记忆
    if failure_monitor(obs) > TAU_FAIL:
        M_f.log(obj=obs.focus, skill=state.plan.skill, sig=state.fail_sig)
        state.need_plan = True
    return q_cmd
